 ## 解决方案
 ## 问题理解

 我们得到了一系列怪物，每个怪物都由一对值描述：它的攻击强度和它的生命值。 我们控制一个战士，他一开始就拥有一定的初始力量和有效的无限生命值，所以生存不是为了死亡，而是为了最大限度地减少战士在清除所有怪物时积累的伤害。 

当我们与怪物战斗时，战斗会从战士开始交替进行。 每次攻击都会根据攻击者的力量减少对手的生命值，战斗会持续到一方的生命值达到零或更低。 由于我们总是先击中，所以一旦顺序固定，战斗的结构就是确定的。 

一个关键机制彻底改变了这个问题：击败怪物后，战士的力量变得等于该怪物的力量。 因此，我们选择怪物的顺序不仅决定了每次战斗中受到的即时伤害，还决定了未来的伤害概况，因为更强的怪物可以减少后续战斗中的伤害。 

目标是选择所有怪物的排序，使战士在所有战斗中受到的总伤害最小化。 

约束 n 高达 100000 意味着任何在排列上具有二次行为的解都是不可能的。 即使 O(n^2 log n) 在实践中也已经太大了。 这立即排除了任何暴力排序或子集上的 DP。 我们需要更接近 O(n log n) 或 O(n) 的东西。 

一个微妙的边缘情况来自这样一个事实：力量只有在赢得战斗后才会增加。 一个天真的贪婪的想法，比如总是选择最弱或最强的下一个怪物，可能会失败，因为最好的选择取决于当前的强度和尽早解锁更高未来强度的潜力。 

例如，考虑这样一种情况：击败稍弱的怪物非常“便宜”，并且会提供很大的力量提升，而更强的怪物则很昂贵并且会延迟这种提升。 如果选择不正确，我们可能会永久地使自己在随后的所有战斗中受到高额伤害。 

## 方法

 暴力方法是尝试怪物排序的所有排列，模拟每次战斗，并计算总伤害。 每次模拟一个固定的顺序需要花费 O(n) 时间，并且有 n！ 可能的订单，因此总工作量为 O(n!·n)，即使 n 约为 10，这也几乎立即变得不可行。 

为了超越这一点，我们需要了解到底是什么造成了损害。 在战斗中，如果我们从力量S开始，面对力量A、生命值H的怪物，击杀它所需的攻击次数由S决定。战士和怪物交替攻击，所以受到的伤害取决于怪物死亡前发生多少次完整攻击。 至关重要的是，更高的力量会以非线性方式缩短战斗时间。 

关键的观察是，击败怪物后，我们的力量会永久增加到该怪物的强度。 因此，问题实际上在于选择一系列强度升级，以最大限度地减少累积成本，其中每个成本取决于当前的强度。 

这种结构建议按力量对怪物进行排序，并按该顺序做出决定。 然而，我们不能简单地按照增加或减少的顺序，因为战斗的伤害取决于使用当前强度减少生命值需要多长时间，并且这与未来的升级相互作用。

解决这个问题的标准方法是将每个怪物重新解释为一项“工作”，其成本取决于当前的强度，并使用总是选择最有利的可用过渡的贪婪排序。 在这个问题中，最优策略简化为按怪物的强度对它们进行排序，并按强度递增的顺序处理它们，因为延迟强度较弱的怪物永远不会有帮助：首先与强度较高的怪物战斗可以更早地获得更好或同等的升级，这只会减少未来的伤害。 

一旦我们接受这个顺序，每场战斗就变成使用当前强度的确定性成本计算，并且我们累积总伤害。

 | 蛮力 | O(n!·n) | O(n!·n) | O(n) | 太慢了 |

 ## 算法演练

 1.将所有怪物按照实力从小到大排序。 这保证了当我们处理一个怪物时，所有之前处理过的怪物的强度都小于或等于当前的，因此强度只会随着时间的推移而增加。 
2.将战士当前的力量初始化为给定的初始值，并将总伤害初始化为零。 
3. 将排序好的怪物一一迭代。 
4. 对于每个怪物，使用当前强度来模拟战斗，以确定在其死亡之前发生多少次怪物攻击。 所需的战士攻击次数由怪物生命值除以当前强度的上限决定。 
5. 根据交换次数，计算怪物攻击战士的次数。 由于战士总是先攻击，因此怪物的攻击次数比完成攻击所需的攻击次数要少。 
6.将该怪物的攻击造成的总伤害添加到全局答案中。 
7.战斗结束后，将战士的力量更新为该怪物的力量。 

### 为什么它有效

 在任何时候，影响未来结果的唯一状态就是当前的实力。 按升序处理怪物可以保证强度单调非递减。 任何偏离此顺序的行为都会不必要地推迟力量的增加，这只能增加或保留未来的战斗长度，因为更高的力量总是会减少或保留任何剩余怪物所需的命中次数。 这种单调性使得贪婪顺序最优。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, s0 = map(int, input().split())
    monsters = []
    for _ in range(n):
        a, h = map(int, input().split())
        monsters.append((a, h))

    monsters.sort()

    s = s0
    total_damage = 0

    for a, h in monsters:
        hits = (h + s - 1) // s
        damage_taken = (hits - 1) * a
        total_damage += damage_taken
        s = a

    print(total_damage)

if __name__ == "__main__":
    solve()
```代码首先根据怪物的强度对它们进行排序，从而强制执行贪婪的结构。 我们维持目前的实力`s`并按顺序处理每个怪物。 

对于每个怪物，我们使用整数上限除法计算需要多少次命中才能将其 HP 降至零。 因为我们先攻击，所以怪物需要`hits`命中将设法准确地攻击我们`hits - 1`次。 每次此类攻击都会造成相当于怪物力量的固定伤害，因此总伤害为`(hits - 1) * a`。 

完成一个怪物后，我们将力量更新为`a`，体现了打败怪物提升实力的问题规律。

 ## 边缘情况

 一个关键的边缘情况是 HP 小于或等于当前强度。 在这种情况下，怪物一次击中就会死亡，造成的伤害为零。 该算法可以正确处理这个问题，因为`(h + s - 1) // s`评估结果为 1，并且`(hits - 1)`变为零，产生零贡献。 

另一个边缘情况是多个怪物具有相同的强度。 排序使它们的顺序在同等条件下保持任意，但由于在此类战斗后强度不会改变，因此无论内部排序如何，伤害计算都保持一致。 

最后，非常大的HP值与较小的初始强度相结合强调了上限划分的正确性。 该公式确保即使生命值不能被强度整除，我们也能正确计算最终的部分命中，从而正确计算怪物的攻击周期。
