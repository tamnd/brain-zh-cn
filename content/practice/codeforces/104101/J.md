 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，两个玩家轮流一次取一个数字，直到序列为空。 爱丽丝先行动。 每个玩家累积他们所选择的数字的总和。 

获取所有数字后，我们计算 Alice 的总数和 Bob 的总数之间的绝对差。 如果这个差是奇数，则爱丽丝获胜，否则鲍勃获胜。 

关键的困难不是拾取过程本身，因为玩家可以自由地拾取任何剩余的元素。 真正的问题是最佳发挥是否会影响最终的平价。 

约束 n 最大可达 1e6，因此任何模拟选择或考虑子集或游戏状态的方法都是不可能的。 我们需要线性或近线性的东西，因为即使 O(n log n) 排序也可以，但任何二次或指数排序都不行。 

一个微妙的一点是，值可以很大，最大可达 1e9，但最终只有奇偶校验很重要。 这通常表明解决方案简化为以 2 为模进行推理，而不是精确求和。 

一种简单的方法是尝试模拟游戏或建模最佳挑选策略。 例如，人们可能认为玩家应该始终选择最大的剩余元素。 这已经导致了错误的推理，因为最佳发挥对于这个问题中最终差异的平价并不重要。 结果仅取决于结构不变量，而不取决于决策。 

另一个不正确的直觉是将其视为标准的“取最大交替”游戏并计算交替和。 但这会失败，因为玩家不受数组末端或任何排序结构的限制。 可以随时采取任何元素，从而消除了所有位置策略。 

隐藏的边缘情况是所有数字都是偶数时。 那么每个总和都是偶数，因此差值始终是偶数，这意味着无论玩什么游戏，鲍勃都会获胜。 相反，如果至少有一个奇数，则最终差值的奇偶性始终为奇数，这意味着爱丽丝获胜。 如果不将问题简化为宇称守恒，这一点并不明显。 

## 方法

 暴力解释将模拟游戏。 在每一步中，玩家选择一个可用的数字并在剩余的多重集上递归，跟踪两个总和。 这实际上是一个游戏树，其中每个状态分支为所有剩余元素。 状态数是 n 的阶乘，因为每个选秀顺序都对应于一个可能的比赛顺序。 

即使使用记忆化，状态空间仍然是指数的，因为剩余的多重集可以用 2^n 子集表示，并且转换取决于轮到哪个玩家。 这使得 n 达到 1e6 时完全不可行。 

关键的观察结果是，选择的顺序不会影响每个玩家在最佳游戏下最终获得的多重数字集，因为对于可以采用哪个元素没有限制。 序列的每个排列都对应于有效的播放顺序。 这意味着爱丽丝和鲍勃之间的最终数字分配没有以有意义的方式进行战略控制。 

我们不考虑最优选择，而是考虑总和的奇偶性。 令 S 为所有数字的总和。 由于 Alice 和 Bob 分割了所有元素，因此我们有 S1 + S2 = S。我们关心的值是 |S1 − S2|，等于 |S − 2S2|。 模 2，这大大简化了：2S2 始终是偶数，因此差值的奇偶校验恰好是 S 的奇偶校验。 

因此，整个游戏就简化为检查总和是奇数还是偶数。 如果和是奇数，则差也是奇数，所以爱丽丝获胜。 如果总和相等，则鲍勃获胜。

 ## 算法演练

1. 计算序列中所有元素的总和。 这是有效的，因为每个元素最终都会被一名玩家拿走，因此无论游戏顺序如何，总和都是固定的。 
2. 通过检查其最低有效位来确定该总和是奇数还是偶数。 只有奇偶性才重要，因为获胜条件取决于绝对差值是否为奇数。 
3. 如果和为奇数，则输出“Alice”，否则输出“Bob”。 这直接从总和的奇偶性与最终差的奇偶性之间的等价性得出。 

### 为什么它有效

 关键的不变量是，无论玩家如何选择元素，所有元素的总和都会保留。 由于 S1 + S2 = S 始终成立，因此表达式 |S1 − S2| 可以重写为 |S − 2S2|。 2S2 项始终是偶数，因此不会影响奇偶校验。 因此，最终比分的平局在比赛开始前就已确定，不取决于任何决定。 这完全消除了游戏方面，并将问题转化为单遍计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    arr = list(map(int, input().split()))
    
    total = sum(arr)
    
    if total % 2 == 1:
        print("Alice")
    else:
        print("Bob")

if __name__ == "__main__":
    main()
```实现是直接的：我们在一次传递中累积所有数字的总和。 对于 n 到 1e6 的情况，使用 Python 的内置 sum 已经是线性且高效的。 我们避免任何排序或模拟，因为它们是不必要的。 

唯一微妙的细节是确保中间逻辑不会干扰奇偶校验。 我们不需要跟踪转弯或模拟移除，因为最终结果仅取决于完整的多重集。

 ## 边缘情况

 最小的单元素案例立即暴露了核心规则。 用于输入`1 1`，Alice取唯一的元素，差值是1，是奇数，所以Alice赢了。 该算法计算出 sum = 1 并正确输出 Alice。 

对于单个偶数元素，例如`1 2`，Bob 获胜，因为总和是 2，偶数。 Alice拿了2，Bob什么也没得到，差值是2，仍然是偶数。 该算法一致地返回 Bob。 

具有许多奇数的情况，例如`1 1 1 1`产生总和 4。即使玩家交替选择，任何划分都会导致平等平分，并且差异是偶数。 该算法直接捕获这一点，而不模拟任何动作。 

这些例子证实，没有任何战略游戏会改变平价结果，并且基于总和的减少就足够了。
