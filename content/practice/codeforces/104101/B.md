 ## 解决方案
 ## 问题理解

 我们正在模拟一个游戏角色，其健康状况根据时间顺序事件日志随时间变化。 角色从初始生命值开始，并在升级时获得额外的生命值。 在某些时候，他们还可能购买一种特殊物品，永久增加他们的生命值并解锁被动能力。 

获得该物品后，每当角色攻击敌人时，如果该敌人当前未处于冷却状态，则可能会触发被动。 当它触发时，它会根据角色当前的健康状况计算伤害值，然后将该伤害的一部分转换回治疗效果。 治疗效果会立即添加到角色当前的健康状况中，从而影响未来的计算。 

输入是按时间递增顺序排序的带时间戳的事件序列。 每个事件要么是增加固定数量生命值的升级，要么是给予大量固定生命值奖励并启用被动的购买事件，要么是对五个可能的敌人之一的攻击，根据冷却状态，可能会或可能不会触发被动。 每个敌人的冷却时间都是独立跟踪的，这意味着攻击不同的敌人不会干扰彼此的冷却计时器。 

输出只是按顺序处理所有事件后的最终健康值。 

约束足够小，直接模拟就足够了。 最多有 1000 个事件，并且时间在 60 分钟窗口内以秒粒度给出，因此即使每个事件的工作量恒定的简单 O(m) 模拟也很容易足够快。 

主要的微妙之处在于正确处理每个敌人的冷却逻辑，并确保被动仅在购买物品后应用。 另一个常见的错误来源是被动内部的操作顺序：伤害取决于攻击时的当前健康状况，并且在计算伤害之后而不是之前应用治疗。 

一个幼稚的错误就是忘记冷却时间是针对每个敌人的。 例如，如果 00:10 的一次攻击击中敌人 1，然后 00:20 的另一次攻击击中敌人 2，则如果该物品处于活动状态，则第二次攻击仍应触发敌人 2 的被动，即使自第一次触发以来已经过去了 10 秒。 

另一个微妙的情况是冷却时间边界。 如果在时间 t 触发攻击，则在时间 t + 29 时不应触发对同一敌人的第二次攻击，但在时间 t + 30 时应再次允许。 

## 方法

 最直接的方法是完全按照描述模拟时间线。 我们维护角色当前的生命值、是否已购买该物品以及每个敌人上次触发被动的时间。 

对于每个事件，我们将其时间戳解析为秒并按顺序处理。 升级事件只是增加固定数量的生命值。 购买物品会增加固定奖励并启用未来的被动计算。 攻击事件检查该物品是否处于活动状态以及该敌人的冷却条件是否满足。 如果两者都成立，我们将使用当前生命值计算伤害，将治疗计算为该伤害的下限百分比，并将其添加到生命值中。 我们还更新了该敌人的最后触发时间。 

蛮力变体在结构上不会有太大差异，因为输入大小已经很小。 唯一假设的低效率是不必要地重新计算时间解析或扫描先前的事件，但即使这样也会保持在限制范围内。 真正的改进是概念性的：跟踪每个敌人的状态允许在 O(1) 内处理每个事件。

 ## 算法演练

我们将所有时间戳转换为秒以简化比较，因为冷却逻辑仅取决于差异。 

1. 将当前生命值初始化为H1，并将该物品标记为未购买。 还初始化一个大小为 5 的数组last_trigger，填充一个非常负的值，以便早期攻击始终通过冷却检查。 
2. 按时间顺序处理事件。 
3. 如果该事件是升级事件，则将生命值增加 H2。 
4. 如果该事件是购买事件，则将生命值增加 800 并将该物品标记为活动状态。 
5.如果事件是攻击敌人x，首先检查该物品是否已购买。 如果不是，则攻击不会执行任何操作。 
6. 如果该物品处于活动状态，请使用条件 current_time - last_trigger[x] >= 30 检查敌人 x 的冷却时间。如果失败，则忽略该攻击。 
7. 如果冷却时间允许，则将伤害计算为 125 + 下限(0.06 * current_health)。 
8. 将治疗量计算为下限（0.1 * 伤害），然后将其添加到当前生命值中。 
9. 将last_trigger[x]更新为当前时间。 

关键思想是健康变化会立即影响后续事件，包括后来的伤害计算，因此我们必须就地更新它。 

### 为什么它有效

 在每个时刻，模拟都会维护事件历史记录所暗示的游戏的准确状态：当前健康状况、物品可用性和每个敌人的冷却状态。 每个事件仅根据当前状态和事件本身确定性地转换此状态。 由于事件按照时间递增的顺序进行处理，并且每次更新都完全符合游戏规则，因此未来的事件不会依赖于未处理的信息，从而保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def parse_time(s):
    mm, ss = s.split(":")
    return int(mm) * 60 + int(ss)

def solve():
    H1, H2, m = map(int, input().split())
    
    hp = H1
    item = False

    last = [-10**9] * 5

    for _ in range(m):
        parts = input().split()
        t = parse_time(parts[0])
        typ = int(parts[1])

        if typ == 2:
            hp += H2

        elif typ == 1:
            hp += 800
            item = True

        else:
            x = int(parts[2]) - 1
            if not item:
                continue
            if t - last[x] < 30:
                continue

            damage = 125 + int(0.06 * hp)
            heal = int(damage * 0.1)

            hp += heal
            last[x] = t

    print(hp)

if __name__ == "__main__":
    solve()
```实现直接遵循事件驱动结构。 每个事件的时间都会转换为秒，这避免了重复解析的复杂性。 

冷却时间检查使用严格的不平等`t - last[x] < 30`，这相当于强制执行 30 秒的最小间隙。 与健康相关的计算完全按照问题陈述的要求使用整数截断。

 ## 边缘情况

 一个重要的边缘情况是在购买商品之前进行攻击。 在这种情况下，即使冷却逻辑允许攻击，也必须完全忽略攻击。 模拟通过检查来处理这个问题`item`在任何计算之前标记。 

另一个边缘情况是在冷却时间的边界上重复攻击。 如果一次攻击发生在时间 t，另一次攻击发生在 t + 30，则第二次攻击必须触发。 条件`t - last[x] < 30`正确地仅拒绝严格较小的差距，因此平等通过。 

最后一个边缘情况是多次升级和之前的治疗后伤害对当前健康状况的依赖。 由于生命值在每次事件发生后立即更新，因此伤害公式始终反映攻击时的正确状态，即使同一分钟内发生多个事件也是如此。
