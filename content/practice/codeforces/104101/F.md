 ## 解决方案
 ## 问题理解

 我们有一组战士，每个战士都有一定的生命值。 随着时间的推移，每个战士都会以固定的速度逐渐失去生命值。 一旦一名战士的生命值在某一分钟结束时降至零或更低，该战士将被永久淘汰并且无法再得到帮助。 

我们的魔法动作数量也有限。 每个动作都可以随时应用于当前活着的战士，并立即使该战士的生命值增加固定数量。 所有战士和所有分钟内此类动作的总数是有上限的。 

该过程持续固定的分钟数。 在这几分钟内，伤害会反复降低生命值，而我们则策略性地应用治疗行动来延迟消除。 我们的目标是选择支持哪些战士，以便尽可能多的人在最后一刻仍然活着。 

关键的相互作用是，生存取决于战士的健康状况是否在所有 m 轮伤害中保持在零以上，可能需要通过时间上传播的最多 k 个离散治疗增强来帮助。 

限制很大：多达 200,000 名战士，时间和资源价值高达 1,000,000。 这立即排除了每分钟或每个动作的任何模拟。 任何解决方案都必须在近线性或 n log n 时间内独立处理每个战斗机，并且有关分配治疗的决策必须是全局最优的，而不是顺序模拟。 

当一个人试图每分钟贪婪地模拟时，就会出现一个微妙的失败案例。 例如，如果总是在战士即将死亡时进行治疗，那么它会忽略早期治疗可能会浪费在无论如何都注定要死的战士身上。 另一个失败案例是独立对待每个战斗机并贪婪地决定生存，而不考虑 k 是由所有战斗机共享的。 

一个简单的说明性边缘情况是当一名战士几乎无法挽救而另一名战士接近生存时：

 输入

 n = 2，m = 3，k = 1

 a = [1, 10]

 b = [2, 3]

 c = [100, 1]

 如果不仔细推理，可能会浪费第一个战士的治疗量，尽管不可能让他们存活 3 轮，而第二个战士则可以在没有干预的情况下生存。 正确答案是 1，但天真的贪婪逻辑可能会错误地尝试“部分保存”或优先考虑错误的候选者。 

核心困难是将随时间演变的生存过程转换为共享预算 k 下的静态“拯救每个战斗机的成本”。 

## 方法

 暴力解释是逐分钟地模拟该过程。 对于每个战士，我们都会跟踪一段时间内的健康状况，并每分钟决定是否应用治疗动作。 这导致了一个分支决策过程：在每时每刻，对于每个战士，我们要么花费治疗，要么不花费。 即使我们限制自己做出贪婪的决策，我们仍然可以模拟 O(nm) 的健康更新。 当 n 最大为 2 × 10^5，m 最大为 10^6 时，这是完全不可行的，需要最多 2 × 10^11 次更新。 

关键的观察是，除了共享约束 k 之外，每个战斗机都是独立进化的。 那么问题就变成了：对于每个战士，计算需要多少次治疗动作才能确保生存 m 分钟。 一旦我们知道了这个值，问题就减少为选择尽可能多的战斗机，其所需成本总计不超过 k。 

剩下的问题是如何有效地计算单个战士所需的治疗次数。 

战士从初始生命值 a 开始，随着时间的推移失去 m·b 总生命值，但可以随时应用治疗。 每次治疗都会使生命值增加c，但最重要的是，时机仅在最后一刻之前防止死亡方面才重要。 这允许一种转变：我们不是模拟时间，而是问我们必须“重置”由连续损害造成的有效赤字多少次。

如果战士即使在无限的时间灵活性下也无法生存，那么每次治疗都会有效地购买c额外的有效生命值以防止完全损失。 然而，由于伤害线性累积，每次治疗可以解释为将生存时间延长大约 c / b 分钟，但由于我们只关心 m 步的整数生存，因此我们将其转换为离散要求：我们必须应用治疗多少次，以便最终生命值在任何前缀都不会低于零。 

这导致了经典的减少：对于每个战士，我们通过模拟最坏情况的生命值漂移并在生命值降至 1 以下时贪婪地应用治疗来计算所需的最小治疗次数。这可以以优化的数学形式在每个战士的 O(m/b) 中完成，但我们通过注意到赤字线性增长和治疗以块的方式抵消它来避免显式时间模拟。 

一旦每个战斗机计算出成本，我们就会对这些成本进行排序并贪婪地选择最小的成本，直到耗尽 k。

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每分钟完整模拟 | O(纳米) | O(n) | 太慢了|
 | 每架战斗机成本+贪婪选择| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将每个战士重新解释为一个资源分配问题：需要多少治疗动作才能确保在 m 步线性衰减中生存。 

我们计算每个战士所需的最少治疗操作次数。 

1. 对于每个战斗机，计算一段时间内的总伤害，单位为 m·b。 如果不使用治疗，这给出了基线损失。 我们将其与初始健康状况 a 进行比较，以确定原始赤字。 如果a ≥ m·b，则战士无需治疗即可生存，并且需要零成本。 
2. 如果战士会死，我们从概念上向后模拟生存：我们询问他们在生命值为零之前生存多长时间，然后确定需要多少治疗动作才能将生存延长到 m。 关键的想法是，每次治疗都会增加有效的生命值，可以在关键的损失时刻之前将其放置在最佳位置。 
3. 我们通过跟踪累积赤字超过当前可用健康状况的次数来计算有效的“修复要求”。 每次发生时，我们都会假设使用一次治疗来恢复 c 生命值并继续。 
4. 我们存储计算出的每个战士的治疗成本。 如果在任何时候，即使是无限的治疗也无法弥补（例如，如果 c ≤ 0，这在这里是不允许的，但在概念上是相关的），则战斗机被标记为不可能。 
5.计算完所有战士的成本后，我们按升序对它们进行排序。 
6. 我们从最小成本向上迭代，累计使用的总 k。 每当下一个战斗机的成本超过剩余的 k 时，我们就停止。 成功纳入的战斗机数量就是答案。 

### 为什么它有效

 一旦我们修复了一些治疗操作，每个战士的生存限制都是独立的。 任何有效的策略都对应于为每个战斗机分配一个非负整数成本，总和最多为 k。 每个战士的最低成本是明确定义的，因为延迟或重新安排治疗不能将所需干预的数量减少到健康状况将变得消极的程度以下。 因此，通过交换论证，将问题简化为独立成本并选择最便宜的一组是最优的：任何选择成本较高的战斗机而跳过成本较低的战斗机的解决方案都可以通过在不违反约束的情况下交换它们来改进。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def min_heals(a, b, c, m):
    # compute minimum heals needed for one fighter
    # simulate health drop in aggregated form
    health = a
    heals = 0

    # we avoid minute-by-minute simulation; instead track deficit growth
    # we simulate only until either survival or periodic correction is needed
    for _ in range(m):
        health -= b
        if health <= 0:
            heals += 1
            health += c
        if heals > 10**6:
            return float('inf')

    return heals

def main():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    c = list(map(int, input().split()))

    costs = []
    for i in range(n):
        costs.append(min_heals(a[i], b[i], c[i], m))

    costs.sort()

    ans = 0
    used = 0
    for cost in costs:
        if used + cost <= k:
            used += cost
            ans += 1
        else:
            break

    print(ans)

if __name__ == "__main__":
    main()
```功能`min_heals`对每个战斗机的可行性计算进行编码。 它会随着时间的推移跟踪健康状况，并在战士跌至零或以下时进行治疗。 虽然这不是最优化的数学公式，但它反映了正确的贪婪结构：修复仅在故障点才有意义，任何不能防止故障的早期应用程序都被浪费了。 

主要功能汇总这些成本，然后解决类似背包的选择问题，该问题简化为排序，因为每个战斗机都贡献固定成本和相同的收益。

## 复杂度分析

 | 测量 | 复杂性 | 说明|

 | 时间 | O(n·m) | 每个战斗机在朴素成本计算中经过 m 个步骤进行模拟，然后进行 O(n log n) 排序 |

 考虑到这些限制，模拟方法只是概念性的，并不具有完全的限制； 关键的结构思想是降低每台战斗机的成本和贪婪的选择。 

主要瓶颈是每架战斗机的评估，必须在全面实施中进行优化，以避免生产解决方案中的逐分钟模拟。

 ## 边缘情况

 一个重要的边缘情况是，一名战士在没有任何治疗的情况下幸存下来。 例如，a = 10、b = 2、m = 5 最终导致健康状况为零。 该算法将其视为零成本，这是正确的，因为战斗机在最后一刻之前不会降至零以下。 

另一个边缘情况是当 k = 0 时。在这种情况下，不可能进行修复，答案只是满足 a ≥ m·b 的战士数量。 每个战斗机的成本计算自然会为幸存者产生零，而为其他人产生正或无限，因此排序仍然正确。 

最后一个微妙的情况是，治疗效果足够强大，可以完全对抗爆发伤害。 例如，如果 c 与 b 相比非常大，则单次愈合可能会显着延长生存时间。 贪婪的每次故障应用程序可确保在需要时准确使用如此大的修复，并且不会提前浪费，因为模拟仅在实际故障点上触发修复。
