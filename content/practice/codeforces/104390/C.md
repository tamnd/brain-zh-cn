 ## 解决方案
 ## 问题理解

 我们得到一个代表一行供应商的二进制字符串。 每个位置都会贡献一颗真宝石或假宝石。 通过选择该绳子的任何连续部分来形成项链。 对于每个这样的部分，专家会移除所有假零件，并仅保留该部分内最长的连续真正宝石块。 如果某个部分不包含真正的宝石，则其贡献为零。 

我们必须计算每个子数组的值并对所有子数组求和$O(N^2)$段，但是$N$可以大到$10^6$，因此枚举段是不可能的。 任何二次方法都需要大约$10^{12}$最坏情况下的操作，远远超出了实际极限。 

一个关键的困难是，一个细分市场的“价值”不能以简单的方式相加。 这取决于该段内“T”的最长连续运行，而不仅仅是计数。 这使得朴素前缀和不够。 

一些边缘案例揭示了为什么直接推理会失败。 例如，如果字符串全是“T”，则每个段都贡献其完整长度，答案将成为所有子数组长度的总和，即$N(N+1)(N+2)/6$。 如果字符串全部为“F”，则每个段贡献为零。 尝试计算每个索引的贡献而不跟踪边界的简单解决方案将打破混合模式，例如`TFTTFT`，其中运行是分散的。 

核心隐藏结构是只有“T”的最大连续块才重要，因为在固定块内，贡献仅取决于段可以扩展到该块的多远。 

## 方法

 暴力方法考虑每一对$(l, r)$，扫描该段，找到最长的连续“T”，并将其长度添加到答案中。 这是正确的，但需要扫描每个段，给出$O(N)$每个段的工作量和$O(N^3)$总时间，对于大量输入来说是不可用的。 

我们可以通过扭转观点来改进这一点：我们不再考虑每个片段，而是考虑每个连续的“T”。 假设我们隔离一个长度为“T”的最大块$k$。 任何线段仅在与该块相交时才对该块做出贡献，并且在该线段内，最佳贡献是与该块的重叠，除非其他地方存在更长的运行。 

关键的观察是，对于每个“T”位置，可以通过考虑有多少子阵列将其视为最大“T”段的一部分来计算贡献。 这可以使用对运行的贡献计数来重新构建：每个运行长度$k$贡献基于有多少子数组包含一个子段，该子段的最佳“T”块恰好位于该运行内部。 

我们不是对每个子数组进行推理，而是使用组合计数来独立计算每次运行的贡献，计算子数组可以向左和向右延伸多远，同时保持此运行作为主要的连续“T”段。 

我们预先计算每个最大“T”段的边界。 对于每个这样的段$[L, R]$，我们计算连续“T”的“最佳”段位于该块内的所有子数组的贡献。 这将问题简化为对运行和边界距离的线性处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(N^3)$|$O(1)$| 太慢了 |
 | 基于运行的贡献计数 |$O(N)$|$O(N)$| 已接受 |

 ## 算法演练

 我们通过将字符串分解为“T”的最大连续段来处理该字符串。 对于每个这样的片段，我们根据其位置和大小计算它如何对最终答案做出贡献。 

1. 扫描字符串并提取连续“T”的所有最大游程。 对于每次运行，记录其左右边界。 此步骤隔离了可以来自有效贡献的独立区域。 
2. 对于每次运行$[L, R]$，计算它的长度$k = R - L + 1$。 该游程充当许多子数组内最长连续实数段的候选者。 
3. 计算有多少个子数组包含此运行，且其中没有完全包含更大的竞争运行。 这是通过从任意位置延伸左边界来完成的$l \le L$和任意位置的右边界$r \ge R$。 这样的子数组的数量是$L \times (N - R + 1)$。 这会计算完全覆盖运行的所有子数组。 
4. 在每个这样的子阵列中，该运行的贡献取决于它如何与周围的“F”块交互。 由于任何“F”都会破坏连续性，因此子数组内最长的连续“T”段正是与该游程的交集，前提是同一子数组内不存在更大的游程。 
5. 将有效子数组的数量乘以游程长度$k$，累积到答案中。 
6. 对所有运行的贡献求和。 

关键的简化是每次运行都可以独立处理，因为任何“F”都会分隔运行并防止合并。 

### 为什么它有效

 每个子数组都有一个独特的分解，分解为具有最大“T”游程的交集。 子数组内最长的连续“T”段必须完全来自这些运​​行之一，因为“F”字符会破坏连续性。 因此，每个贡献都被唯一地分配给一次运行。 通过计算有多少子数组选择给定的运行作为其最大贡献者并乘以其长度，我们可以避免重复计算并确保完整性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input().strip())
    s = input().strip()

    runs = []
    i = 0

    while i < n:
        if s[i] == 'T':
            j = i
            while j < n and s[j] == 'T':
                j += 1
            runs.append((i, j - 1))
            i = j
        else:
            i += 1

    ans = 0

    for L, R in runs:
        k = R - L + 1

        left_choices = L + 1
        right_choices = n - R

        ans += k * left_choices * right_choices

    print(ans)

if __name__ == "__main__":
    main()
```该实现首先将字符串压缩为“T”的运行。 每次运行都是独立处理的。 对于从索引处开始的运行$L$并结束于$R$，我们计算有多少个子数组完全包含它，即$(L+1)(n-R)$。 乘以游程长度即可得出其总贡献。 

微妙的部分是索引处理。 由于索引是从零开始的，因此有$L+1$有效的左端点和$n-R$有效的右端点。 缺少 +1 移位是一种常见的差一错误。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input().strip())
    s = input().strip()

    runs = []
    i = 0
    while i < n:
        if s[i] == 'T':
            j = i
            while j < n and s[j] == 'T':
                j += 1
            runs.append((i, j - 1))
            i = j
        else:
            i += 1

    ans = 0
    for L, R in runs:
        k = R - L + 1
        ans += k * (L + 1) * (n - R)

    return str(ans)

# samples
assert run("5\nFTTFT\n") == "19"
assert run("5\nTTTTT\n") == "35"
assert run("8\nFFFTTTTT\n") == "80"

# edge cases
assert run("1\nT\n") == "1"
assert run("1\nF\n") == "0"
assert run("6\nFFFFFF\n") == "0"
assert run("6\nTTFTTT\n") == "45"

 ## 边缘情况

 对于单个字符输入，例如`T`，该算法形成长度为 1 的一次游程。恰好有一个子数组，并且它完全包含该游程，产生贡献 1，与公式匹配$(0+1)(1-0)\cdot1$。 

对于像这样的全假字符串`FFFF`，没有找到运行。 该循环不产生贡献，因此结果为 0，无需特殊处理。 

对于交替结构，例如`TFTFTF`，每个“T”被隔离为长度为 1 的游程。每个游程根据其位置独立贡献，并且该公式正确地累积贡献而不合并，因为“F”确保分离。
