 ## 解决方案
 ## 问题理解

 我们有两个有序的赛车手列表，其中每个赛车手都有独特的声望值。 任务是通过从第一个列表的前面或第二个列表的前面重复选择下一个赛车手来构建单个最终阵容，总是一次消耗一个元素。 目标是形成一个组合序列，该序列尊重基于两个列表当前前沿的声望比较的贪婪偏好规则。 

每一步，只有每个列表中剩下的第一个赛车手很重要。 我们决定将哪一个放在合并序列中的下一个，然后将其从列表中删除。 该过程将继续，直到两个列表都用完为止。 

此类合并问题中典型约束的重要含义是线性：如果赛车手总数达到 200000 左右，则 O(nm) 或 O((n+m)²) 策略立即不可行。 唯一可行的方向是一种算法，该算法最多一次通过两个列表，产生 O(n + m) 解决方案。 

当其中一个列表过早变空时，就会出现一种微妙的边缘情况。 总是比较头而不检查空性的幼稚实现将会失败。 例如，如果 A 为空而 B 仍有元素，则唯一有效的操作是从 B 获取。另一个边缘情况是第一个元素的值相等。 尽管该问题在全局范围内具有唯一性，但实现有时会假设相等处理并引入不必要的分支，从而破坏排序逻辑。 

## 方法

 强力解释是模拟交错两个列表的所有可能方式。 每一步最多有两个选择，因此在最坏的情况下，我们探索高度为 n + m 的二元决策树。 这导致指数复杂度，大约为 O(2^(n+m))，即使对于超过几十个元素的非常小的输入，这也是不可能的。 

关键的观察是我们实际上不需要探索这两种选择。 在任何步骤中，我们只关心当前哪个前缀选择会导致字典顺序更好的结果序列。 由于所有值都是不同的，因此比较剩余后缀在本地会减少为仅比较当前头。 一旦一个头严格小于另一个头，首先选择它总是会产生一个全局更好的前缀，因此在未来的任何延续中都不会更差。 

这种局部最优性将整个决策过程折叠成一个简单的贪婪合并，类似于合并两个已排序的数组，只不过顺序是通过头比较而不是固定排序动态确定的。 

我们维护两个指针并重复获取较小的当前头，从而推进该指针。 当一个列表耗尽时，直接追加另一个列表的剩余元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^(n+m)) | O(2^(n+m)) | O(n+m) | 太慢了|
 | 最优贪心合并 | O(n+m) | O(1) 额外 | 已接受 |

 ## 算法演练

 我们使用两个索引来模拟合并过程，每个索引对应一个列表。 

1. 在数组 A 和 B 的开头初始化两个指针 i 和 j。它们代表每个列表中第一个未消耗的赛车。 
2. 当 i 在 A 内并且 j 在 B 内时，比较 A[i] 和 B[j]。 选择较小的值作为输出序列中的下一个赛车。 此选择是正确的，因为当所有值都不同时，任何后续决策都不依赖于跳过较小的可用前缀。 
3. 如果 A[i] 较小，则将其附加到结果中并递增 i。 否则追加 B[j] 并递增 j。 这确保了每一步仅消耗一个元素，从而保持线性进度。 
4. 当一个指针到达其数组末尾时，按顺序附加另一个数组的所有剩余元素。 此时已别无选择，因为只剩下一个来源。

为什么有效：在每一步中，决策都是在每个列表中最早剩余元素的两个候选元素之间进行的。 由于所有值都是唯一的，因此选择较小的头总是会产生按字典顺序排列的较小合并序列的前缀。 任何替代选择都会立即增加第一个不同的位置，并且未来的交换无法修复该顺序，因为后面的元素无法在序列中移动到前面。 这建立了与最优子结构相结合的贪婪选择属性，保证始终采用较小的可用头的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    i = j = 0
    res = []
    
    while i < n and j < m:
        if a[i] < b[j]:
            res.append(a[i])
            i += 1
        else:
            res.append(b[j])
            j += 1
    
    while i < n:
        res.append(a[i])
        i += 1
    
    while j < m:
        res.append(b[j])
        j += 1
    
    print(*res)

if __name__ == "__main__":
    solve()
```该解决方案是围绕两个在数组中独立移动的指针构建的。 仅当两个列表仍具有元素时，主循环才会继续，以确保每次比较都有意义。 每次迭代仅消耗一个元素，因此不会重新访问任何元素。 

最后两个循环处理耗尽情况。 它们是必要的，因为一旦一个数组为空，就不可能进行进一步的比较，并且所有剩余元素必须按顺序附加。 

一个常见的实现错误是忘记合并循环必须在任一指针达到其限制时停止，而不是同时达到限制。 另一个微妙的问题是错误地处理相等性，但这里的唯一性保证了严格的排序，因此 else 分支可以安全地处理所有剩余的情况。

 ## 边缘情况

 当一个列表从一开始就是空的时，算法会完全跳过比较循环并直接输出另一个列表。 对于输入 A = [] 和 B = [4, 1, 2]，指针 i 保持在 0，而 j 从 0 前进到 3，完全按照要求生成 [4, 1, 2]。 

当一个列表的所有元素都小于另一个列表时，算法始终首先耗尽该列表。 对于 A = [1, 2, 3] 和 B = [10, 11]，每次比较都从 A 中进行选择，直到穷尽为止，然后附加 B。 指针仅向前移动的不变性确保不会跳过任何元素或错误地重新排序。 

当交错最大时，例如 A = [1, 3, 5, 7] 和 B = [2, 4, 6, 8]，每个步骤在数组之间交替。 该算法无需额外分支即可处理此问题，因为每次比较都会独立解析下一个最小的头，即使在紧密交替的情况下也能保持正确性。
