 ## 解决方案
 ## 问题理解

 该问题可以理解为探索房间定向系统中的连通性。 每个房间代表图中的一个节点，每个单向通风口代表从一个节点到另一个节点的有向边。 从房间 1 开始，我们被要求确定通过重复遵循这些定向连接最终可以访问多少个不同的房间。 

因此，输入描述了一个有向图：房间是顶点，通风口是边。 输出是一个数字，即从顶点 1 开始的可到达顶点集的大小。 

从约束的角度来看，这是经典的线性或近线性图遍历设置。 即使没有明确的边界，这种形式的 Codeforces 图问题通常也允许最多 10^5 或 2 × 10^5 顶点和边。 这立即排除了任何二次方的问题，例如检查所有节点对之间的可达性。 尝试从头开始重新计算每个节点的可达性的解决方案将爆炸到 O(n(n + m))，这在典型限制下是不可行的。 

一个微妙的边缘情况来自循环和断开的组件。 不跟踪访问节点的简单递归遍历可能会永远循环。 例如，如果房间 1 通向房间 2，房间 2 通向房间 1，则遍历将无限交替，除非我们明确标记访问过的节点。 

另一个特殊情况是房间 1 没有传出边缘。 在这种情况下，正确答案是 1，因为我们只能留在起始房间。 

## 方法

 一个蛮力的想法是从当前可到达的房间集合中反复扩展。 我们可以从房间 1 开始，然后添加所有可直接到达的房间，然后从这些房间添加它们的邻居，依此类推，重新计算边界，直到没有新房间出现。 如果实施得不好，就会重复扫描所有边以检查它们的起始节点是否已经在可达集中。 在最坏的情况下，每个扩展通道处理 O(m) 条边，并且可能有 O(n) 个这样的通道，从而导致 O(nm) 行为。 

这个问题的结构提出了一个更清晰的观点：一旦一个房间可以到达，它应该只被处理一次，一旦我们探索了它的出口通风口，我们就不需要重新访问它们。 这正是图形遍历的设置，该设置将节点首次发现时标记为已访问。 深度优先搜索或广度优先搜索都自然地强制执行这种“访问一次”属性，并确保每条边最多被遍历一次。 

这减少了将边缘重复扫描为邻接列表的单次扫描，从而产生图大小的线性复杂性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力扩张| O(纳米) | O(n) | 太慢了|
 | DFS/BFS 遍历 | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 我们将房间建模为邻接列表，其中每个房间存储可从其直接访问的所有房间。 

1. 根据输入构建邻接表。 从 u 到 v 的每个定向通风口都存储在 u 的列表中。 这允许有效地枚举传出连接，而无需扫描不相关的边缘。 
2. 创建一个大小为 n + 1 的已访问数组，初始化为 false。 这可以防止重新访问房间，并且对于避免循环图中的无限循环至关重要。 
3. 从房间 1 开始遍历。在探索邻居之前将房间 1 标记为已访问过。 这确保我们永远不会再次排队或递归到其中。 
4. 使用堆栈或队列来管理探索。 弹出一个房间，并迭代其所有即将离开的邻居。 任何尚未访问的邻居都被标记为已访问并添加到结构中以供以后处理。 
5. 继续，直到没有更多空间可供处理。 至此，所有可达节点都已被恰好发现一次。 
6. 计算访问数组中有多少条目为真。 该计数是不同的可到达房间的数量。

堆栈和队列之间的选择并不影响正确性。 DFS 首先探索更深的路径，而 BFS 逐级探索，但两者都保证完全的可达性覆盖，因为它们沿着每个发现节点的所有传出边缘系统地扩展。 

### 为什么它有效

 关键的不变量是每个标记为已访问的房间都可以从房间 1 到达，并且每个可到达的房间最终都会被标记为已访问。 我们通过仅在我们第一次通过来自已可达节点的有效有向边发现节点时标记已访问的节点来维护这一点。 由于我们从不重新访问节点，因此每个节点最多被处理一次，并且最终会探索来自可达节点的所有传出边。 这保证了不会遗漏任何可达节点，也不会错误地包含不可达节点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].append(v)
    
    visited = [False] * (n + 1)
    stack = [1]
    visited[1] = True
    count = 0
    
    while stack:
        u = stack.pop()
        count += 1
        
        for v in adj[u]:
            if not visited[v]:
                visited[v] = True
                stack.append(v)
    
    print(count)

if __name__ == "__main__":
    solve()
```邻接表构造是将输入直接转换为图形表示。 访问数组对于防止重新访问节点至关重要，并且它在发现节点时更新，而不是在弹出节点时更新，这避免了堆栈中的重复条目。 

基于堆栈的 DFS 确保我们完全遍历每个连接的可达区域。 每个节点在处理时计数器都会递增一次，与每个节点弹出一次的不变量相匹配。

 | 测量 | 复杂性 | 说明|

 | 时间 | O(n + m) | 邻接遍历时，每个节点被访问一次，每条边被扫描一次 |

 ## 边缘情况

 像这样的自循环情况`1 -> 1`处理得很干净，因为节点 1 在探索开始之前就被标记为已访问。 在处理其邻接表时，邻居已经被访问过，因此被忽略，仅计算节点 1 后遍历结束。 

纯循环例如`1 -> 2 -> 3 -> 1`演示了为什么访问数组是必不可少的。 如果没有它，DFS 将无限期地重新访问节点。 有了它，每个节点都会插入堆栈一次，弹出一次，如果再次遇到则跳过。 

节点 1 没有出边的图会立即处理：堆栈以`[1]`，我们将其弹出，将计数增加一次，并且找不到邻居，结果输出为 1。
