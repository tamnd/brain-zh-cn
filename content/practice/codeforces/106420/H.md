 ## 解决方案
 ## 问题理解

 我们得到了一个类似排列的过程，通过重复合并或“验证”相邻的值段来构建结构。 该问题不是直接模拟该过程，而是询问给定的数字排序是否可以解释为此类合并的有效序列的结果，最终将所有内容减少到从 1 到 N 的一个连续有效范围。 

重新构建任务的一个有用方法是考虑从左到右扫描数组，同时根据值而不是位置来维护连续整数组。 每个元素最初形成一个仅由其自身组成的简单段。 当我们处理更多元素时，如果某些相邻段的值范围完全相邻，则可以合并它们，这意味着一个段以 x 结束，下一个段以 x+1 开始，反之亦然。 最终目标是确定所有元素是否可以折叠成单个连续的数字区间 [1, N]。 

输入是大小为 N 的单个排列，我们必须决定在这些合并规则下该排列是否可以完全减少到区间 [1, N] 中。 输出是一个二元决策，指示这是否可能。 

这些限制以非常直接的方式产生影响。 由于 N 可能很大，任何以嵌套方式重复扫描或检查段邻接性的行为都会退化为二次行为。 反复尝试通过扫描所有当前段来检测有效切割点或合并的简单方法会导致 O(N²) 行为，因为每个新元素都可以触发对当前结构的重新计算链。 

当本地不存在邻接时，会出现微妙的边缘情况。 例如，考虑排列 [2, 4, 1, 3]。 没有一对相邻值以允许早期合并的方式彼此相邻出现，并且结构永远不会稳定为更大的间隔。 幼稚的方法可能仍会尝试基于部分重叠来模拟合并，但此配置永远不会形成有效的完整间隔，因此正确的答案是否定的。 

另一方面，像 [1, 3, 4, 2] 这样的排列确实允许有效的合并序列，即使邻接性在全局范围内并不明显。 关键是合并可以通过中间间隔传播，最终允许完全崩溃。 

## 方法

 蛮力的想法是显式地模拟合并过程。 我们维护当前段的列表，每个段跟踪其包含的最小值和最大值。 在每一步中，我们都会重复扫描段列表，合并值间隔连续的任意两个相邻段。 我们继续下去，直到不可能再进行合并为止。 

这是有效的，因为它直接反映了流程的定义。 然而，每次合并都会触发对段结构的完全重新扫描。 在最坏的情况下，每个元素都会导致线性数量的比较，并且只有在反复重新访问较早的段之后才会发生合并。 这导致了二次复杂度。 

关键的观察是该过程对复杂的全局结构不敏感。 它只关心我们扫掠时能否形成连续的值区间。 每个元素贡献一个单位区间 [x, x]，唯一有意义的操作是合并相邻区间（如果它们在数字上连续）。 这表明我们可以维护一堆间隔并尽可能贪婪地合并。 正确性来自这样一个事实：一旦间隔变得可合并，延迟合并永远不会在以后创建新的可能性，因为未来的元素只会扩展或连接现有的数字边界。 

这通过本地合并将问题减少到单遍。

 | ---| ---| ---| ---|
 | 暴力模拟| O(N²) | O(N) | 太慢了|
 | 堆栈间隔合并| O(N) | O(N) | 已接受 |

## 算法演练

 我们从左到右处理排列，维护一堆不相交的数字间隔。 

1. 对于排列中的每个元素 x，创建一个新的区间 [x, x] 并将其压入堆栈。 这代表在结构中引入一个新的隔离值。 
2. 当堆栈至少包含两个间隔时，检查顶部的两个间隔。 如果它们的值范围在数字意义上相邻，这意味着下限区间的最大值和上限区间的最小值在任一顺序上都恰好相差 1，则将它们合并为跨越这两个区间的单个区间。 我们将这两个区间替换为它们的并集。 
3. 只要栈顶与前一个继续形成有效的连续间隔，就继续合并。 这确保了每一个新创造的整合机会都能立即实现。 
4. 处理完所有元素后，检查堆栈是否已折叠成恰好一个区间。 
5. 如果单个区间正好是[1, N]，则输出YES。 否则输出NO。 

合并规则是算法的核心。 它编码了这样一个事实：只有数字邻接很重要，而不是位置邻接。 一旦两个区间在数字上连续，在任何进一步的推理中它们就无法与单个连续块区分开来。 

### 为什么它有效

 不变的是，在每一步中，堆栈表示将已处理的前缀划分为最大间隔，这些间隔在当前信息下无法进一步合并。 任何有效的最终构造都必须细化此分区，因为合并只能发生在数字相邻的间隔之间，并且堆栈总是立即检测到这些间隔。 

如果将来可能进行合并，那一定是因为两个区间最终在值空间中变得相邻。 然而，这只能通过包含中间值来实现，这已经触发了早期的合并。 这确保了延迟合并永远不会创造新的机会，因此贪婪合并是安全的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    st = []

    for x in a:
        st.append([x, x])

        while len(st) >= 2:
            l2, r2 = st[-1]
            l1, r1 = st[-2]

            if r1 + 1 == l2 or r2 + 1 == l1:
                st.pop()
                st.pop()
                st.append([min(l1, l2), max(r1, r2)])
            else:
                break

    if len(st) == 1 and st[0][0] == 1 and st[0][1] == n:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```该实现保留了一系列间隔。 每个元素都以单例间隔开始，而 while 循环强制执行最大合并。 关键细节是检查两个方向的邻接性，因为间隔可能不会通过插入严格排序。 最终检查确保整个值范围都被覆盖，没有间隙。

 插入 3 后，区间 [4,4] 和 [3,3] 合并，然后 [2,2] 与 [1,4] 合并，生成 [1,4]。 最终堆栈是覆盖所有值的单个区间，因此输出为 YES。

 ## 边缘情况

 一种重要的边缘情况是邻接仅通过传递闭包而不是直接邻居形成。 例如，在 [2, 4, 1, 3] 中，早期不存在直接连续的对，但最终的合并创建了完全覆盖。 堆栈通过推迟合并直到出现所需的邻居来处理此问题，然后将所有内容正确折叠到 [1, 4] 中。 

另一种边缘情况是元素在低值和高值之间交替的排列，例如 [3, 1, 4, 2]。 堆栈暂时保存多个不相交的区间，但一旦出现连接值，它们就会级联合并。 该算法确保中间碎片不会妨碍最终的合并。
