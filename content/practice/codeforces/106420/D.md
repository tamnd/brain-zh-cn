 ## 解决方案
 ## 问题理解

 我们得到了一个非常小的多重字符集，并且要求我们考虑通过重新排列部分或全部这些字符可以形成的每个不同的字符串。 每个字符最多可以使用它在输入中出现的次数，因此我们正在有效地构建输入字母的所有可能的非空子集的所有唯一排列。 

输出基于整个字符串系列的信息聚合。 由于每个有效字符串都会贡献其长度，因此任务减少为生成可以形成的所有不同字符串并每次累加它们的长度。 

关键的结构约束是字符数量极少，最多 8 个。这立即改变了问题的性质。 一般的重复排列问题的输入大小是指数级的，但这里绝对最坏情况的状态空间受 8 个项目的排列数量限制，该数量小到足以直接枚举。 

一个天真的陷阱是忽略重复项。 如果输入包含重复的字母，则不同的构造路径可能会导致相同的字符串。 例如，输入“AAB”会产生两种相同的方式来构建“AAB”，具体取决于首先选择哪个“A”。 如果我们不进行重复数据删除，我们就会过多计算字符串数量和长度总和。 

另一个微妙的问题是计算空结构。 如果我们允许递归终止而不放置任何字符，我们将包含空字符串。 由于它的贡献长度为零，因此它不会影响总和，但如果不明确排除，它可能会使正确性的推理变得复杂。 

## 方法

 暴力方法是将问题视为对字符频率表的回溯枚举。 我们维护可用字母的计数，并通过选择剩余计数的任何字母、附加它并继续来递归地构建字符串。 每次我们到达完整的字符串时，我们都会将其插入到一个集合中，以确保不会多次计算重复项。 

这种方法是正确的，因为每个有效字符串都对应于一些遵守频率约束的选择序列，并且递归会探索所有此类序列。 然而，递归状态的数量增长很快，分支因子高达 8，并且在最坏的情况下构造的字符串的原始数量可以达到 109,600 左右，这仍然是可以管理的，但没有必要过于复杂。 

关键的观察结果是约束 n ≤ 8 使得任何阶乘规模的枚举都可行。 我们可以使用标准排序技术（例如排序多重集表示上的下一个排列）直接生成所有子集长度的所有排列，而不是通过递归状态或哈希集仔细修剪重复项。 这避免了递归开销，并通过依赖排序和集合插入使重复处理变得简单。 

我们本质上是用算法的复杂性来换取暴力枚举，这完全是由微小的输入范围来证明的。

 ## 算法演练

1. 统计输入字符串中每个字符的出现频率。 这为我们提供了可以构建的内容的紧凑表示，而不是使用原始索引。 
2. 使用输入字符串中位置的位掩码生成所有可能的非空字符子集。 由于 n ≤ 8，因此最多有 2^8 − 1 = 255 个子集，这是非常小的。 
3. 对于每个子集，构造与所选索引相对应的字符多重集。 此步骤隔离该子集中使用的确切字母。 
4. 对子集中的字符进行排序。 排序确保可以一致地处理从相同多重集生成的重复排列。 
5. 使用下一个排列逻辑生成此排序列表的所有不同排列。 每个排列对应于该子集的唯一字符串排列。 
6. 将每个生成的排列插入到一个集合中。 该集合保证来自不同子集的相同字符串或重复字母仅计算一次。 
7. 累加集合中存储的所有唯一字符串的长度总和。 
8. 处理所有子集和排列后输出最终总和。 

### 为什么它有效

 每个有效字符串都对应于从原始输入中选择位置的子集，然后排列所选字符。 子集枚举保证考虑每个字母选择，而排列生成则确保每个多重集恰好达到一次排序。 该集合确保即使多个子集选择由于重复字符而导致相同的字符串，也只计算一次。 由于所有有效字符串都被至少一个子集排列路径覆盖，并且由于考虑字符计数而不会生成无效字符串，因此结果是完整且正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from itertools import combinations
from collections import Counter

def solve():
    s = input().strip()
    n = len(s)

    seen = set()

    # enumerate all non-empty subsets via bitmask
    for mask in range(1, 1 << n):
        chars = []
        for i in range(n):
            if mask & (1 << i):
                chars.append(s[i])

        chars.sort()

        # generate permutations of sorted multiset
        used = [False] * len(chars)

        def backtrack(path):
            if len(path) == len(chars):
                seen.add("".join(path))
                return

            for i in range(len(chars)):
                if used[i]:
                    continue
                if i > 0 and chars[i] == chars[i - 1] and not used[i - 1]:
                    continue
                used[i] = True
                path.append(chars[i])
                backtrack(path)
                path.pop()
                used[i] = False

        backtrack([])

    total = sum(len(x) for x in seen)
    print(total)

if __name__ == "__main__":
    solve()
```该解决方案首先使用输入字符串上的位掩码枚举子集。 这是安全的，因为 n ≤ 8，因此即使最多 255 个子集也是微不足道的。 

在每个子集中，我们构建一个排序的字符列表。 排序至关重要，因为它允许我们在排列生成中应用标准的重复跳过规则：当存在两个相同的字符时，如果第一个字符已在当前递归路径中使用，我们仅使用第二个字符。 这可以防止多次生成相同的排列。 

回溯函数构造所选多重集的所有排列。 每个完整路径都插入到一个Python集中，这确保了不同子集之间的全局唯一性。 

最后，我们计算所有唯一字符串的长度总和。 这直接对应于所需的输出。 

一个微妙的点是重复跳过条件取决于排序。 如果不排序，相同的字符将以任意顺序出现，并且修剪条件将失败，导致重复输出。

 ## 边缘情况

 一种边缘情况是所有字符都相同。 对于输入“AAAA”，许多递归路径生成相同的字符串“A”或“AA”，但该集合确保仅计算每个不同字符串的一个实例。 该算法构造子集，但每个大小为 k 的子集仅生成一个由 k 个重复的“A”组成的唯一字符串，因此最终的总和仅为 1 + 2 + 3 + 4。 

另一个边缘情况是所有字符都不同。 在“ABC”中，不会触发重复修剪，因此排列生成是最大的。 每个子集恰好贡献 k！ 字符串，并且子集之间不会发生集合冲突。 

最后一个微妙的情况是混合重复与交错结构，如“AAB”。 如果没有排序排列剪枝条件，“AAB”和“ABA”将被过度生成。 每个子集的排序输入和防止无序重复使用相同字符的条件的组合确保了每个排列在全局集级别的重复数据删除之前恰好生成一次。
