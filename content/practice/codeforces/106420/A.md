 ## 解决方案
 ## 问题理解

 我们得到一个整数$n$，我们想要确定最大的整数$x$使得某种几何或组合构造成为可能。 关键约束将整个问题简化为一个简单的不等式，涉及$x$和$n$: 构建在以下情况下是可行的：$x^2 \le 2n$。 换句话说，我们试图找到最大的整数$x$其平方不超过给定输入的两倍。 

您可以将问题视为分配资源，其中每个单元$n$贡献两个基本槽，以及有效的大小配置$x$消耗$x^2$这些插槽。 任务是推$x$尽可能大，同时保持在可用预算范围内$2n$。 

输入只是这个单个整数$n$。 输出为一个整数，最大可行$x$。 

由于该解决方案纯粹是算术，因此约束$n$主要决定是否必须担心溢出或浮点精度。 对于典型的 Codeforces 边界，其中$n$可以达到$10^{18}$、直接整数乘法和平方根运算在 Python 中仍然是安全的，但在 C++ 中需要小心 64 位算术。 

出现微妙的边缘情况时$n = 0$。 然后$2n = 0$，所以唯一有效的$x$是 0。另一个边界是当$n = 1$， 在哪里$2n = 2$，答案又是 1，因为$1^2 = 1 \le 2$但$2^2 = 4$太大了。 这些案例证实答案并不简单$\lfloor \sqrt{n} \rfloor$，而是取决于$2n$。 

一个幼稚的错误是忘记 2 的因数并计算$\lfloor \sqrt{n} \rfloor$，这低估了所有人的答案$n > 0$。 

## 方法

 蛮力的想法是尝试所有可能的值$x$从0开始递增，直到不等式$x^2 \le 2n$失败。 对于每位候选人$x$，我们计算$x^2$并将其与$2n$。 这是正确的，因为我们明确测试了每个可能答案的可行性，但它可能会降级为$O(\sqrt{n})$迭代以来$x$可以长到大约$\sqrt{2n}$。 虽然这在许多情况下已经可以接受，但当不平等的结构如此直接时，这仍然是不必要的工作。 

关键的观察是条件$x^2 \le 2n$定义单调边界。 一旦值为$x$无效，所有较大的值也无效。 这将问题转化为寻找平方以下列为界的最大整数$2n$，它恰好是整数平方根$2n$。 我们可以直接使用平方根运算并对其进行取整，或者依靠整数运算来避免精度问题，而不是迭代。 

所以问题归结为计算$\lfloor \sqrt{2n} \rfloor$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(\sqrt{n})$|$O(1)$| 太慢但安全|
 | 最佳|$O(1)$|$O(1)$| 已接受 |

 ## 算法演练

 1.读取整数$n$来自输入。 整个问题仅取决于这个单一值，因此不需要额外的解析或预处理。 
2. 计算$m = 2n$。 这将原始状态转变为干净的形式$x^2 \le m$，隔离我们比较的数量。 
3. 计算整数平方根$m$，这是最大的整数$x$这样$x \cdot x \le m$。 这直接对应了可行性的边界。 
4. 输出该值作为最终答案。 

### 为什么它有效

 不平等$x^2 \le 2n$定义一组单调的有效整数：如果$x$有效，那么所有较小的值也有效，并且如果$x$失败，所有较大的值都会失败。 这保证了解正是这个单调谓词的边界点。 整数平方根函数精确找到该边界，确保不会跳过任何有效值，也不包含无效值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import math

def main():
    n = int(input().strip())
    m = 2 * n
    ans = math.isqrt(m)
    print(ans)

if __name__ == "__main__":
    main()
```该实现几乎直接反映了算法。 首先乘以 2 以反映变换后的约束。 然后`math.isqrt`使用而不是浮点平方根以避免大值可能出现的精度错误$n$。 该函数安全地计算整数平方根$O(1)$Python 中的摊销时间。 

一个常见的实施错误是使用`int(math.sqrt(m))`直接地。 虽然它通常有效，但浮点舍入偶尔会产生如下结果$x - 1$对于接近双精度极限的完美平方。 使用`isqrt`完全避免了这种情况。

 ## 边缘情况

 对于$n = 0$，我们计算$m = 0$，所以答案是$\lfloor \sqrt{0} \rfloor = 0$。 该算法自然地处理这个问题，因为`isqrt(0)`返回 0，无需特殊分支。 

为了$n = 1$,$m = 2$，整数平方根为 1。这证实了最小的非零输入已经产生了一个非零答案，这是一个朴素的结果$\lfloor \sqrt{n} \rfloor$方法也会是正确的，但原因是错误的。 

对于非常大的$n$， 例如$10^{18}$,$m$保持在 64 位范围内（$2 \cdot 10^{18}$），Python 的任意精度整数可以安全地处理它。 的计算`isqrt`保持稳定并完全避免浮点错误，因此边界处不会发生精度下降。
