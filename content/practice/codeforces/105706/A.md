 ## 解决方案
 ## 问题理解

 我们得到一个整数数组$A$。 对于任何连续的段$A[L..R]$，我们被要求构造另一个数组$B$具有相同的长度，满足一些结构约束：中的所有值$B$必须为正数，序列必须从左到右非递减，并且每个位置$i$必须避免复制其原始值，意思是$B_i \neq A_i$。 

在所有这些有效的构造中$B$，我们只对最小化最后一个值感兴趣$B_R$。 对于每个查询段，我们计算这个最小可能的最终值。 

关键的难点在于$B$不是由每个指数的公式独立固定的。 非递减约束耦合了所有位置，因此在段的早期选择一个值会限制稍后发生的情况。 每个位置都有效地表示“你必须选择一个不同于$A_i$，但与之前的选择相比，您可以自由地保持不变或增加。”

 约束条件意味着$N$和$Q$测试用例很大，总大小约为$2 \cdot 10^5$。 这排除了任何尝试显式构建的解决方案$B$对于每个查询，因为即使$O(R-L+1)$在最坏的情况下，每个查询都会降级为二次行为。 我们被推向每个查询更接近线性或对数的方向，通常使用预计算或贪婪状态跟踪。 

微妙的边缘情况来自禁止值和单调约束之间的相互作用。 例如，如果$A = [1, 2, 3]$,天真的选择$B = [1, 2, 3]$无效，因为每个位置都匹配，即使它满足单调性。 另一种情况是数组强制“跳跃”时：$A = [1, 1, 1]$， 然后$B = [1, 2, 3]$有效并给出最终值 3，但粗心的贪婪方法可能会错误地重用 1 并陷入违反状态$B_i \neq A_i$在最后。 

## 方法

 直接的暴力方法将尝试构建$B$对于每个查询，通过扫描$L$到$R$。 在每个位置$i$，我们选择最小的整数$\ge B_{i-1}$那不等于$A_i$。 这种贪婪规则是正确的，因为选择比必要值更大的值只会增加未来的约束，而无助于避免禁止值。 

本次施工需要$O(R-L+1)$每个查询。 在最坏的情况下，如果我们对大段有很多查询，这就会变成$O(NQ)$，当两者都能达到时就太大了$2 \cdot 10^5$。 

关键的观察是贪婪过程是确定性的，并且仅取决于当前值和由下式定义的禁止集：$A_i$。 由于状态只是当前值而不是完整的历史记录，因此问题简化为跟踪运行值在反复“跳过”禁止点时如何演变。 这是一个经典的设置，我们可以预先计算转换或压缩跨范围的相同行为，因为每个步骤只是“移动到不小于当前的最小允许值”。 

我们可以将每个位置视为恰好阻塞一个值。 所以在步骤$i$，如果当前值等于$A_i$，我们必须将其加一； 否则我们可以保留它。 这将过程转换为在某些位置强制增量的整数遍历，可以使用基于段或下次出现的推理来有效地模拟。

 ## 算法演练

 实现这个想法的一种简洁方法是独立处理每个查询，但利用以下事实来加速贪婪步骤：我们只在当前值与$A_i$。 

1.从初始值开始$cur = 1$。 我们从 1 开始，因为所有值都在$B$必须是积极的，并且从尽可能小的开始有助于最小化最终答案。 
2. 迭代来自的段$L$到$R$。 在每个索引处$i$， 比较$cur$和$A_i$。 
3.如果$cur = A_i$， 然后$cur$在这个位置是禁止的，所以增加$cur$直到它不再等于$A_i$。 因为我们只增加，所以我们永远不会违反单调性。 
4. 解决职位冲突后$i$，我们保留$cur$作为价值$B_i$。 我们稍后不会减少它，因此序列自动保持非减少状态。 
5. 移至下一个位置。 查询的最终答案是$cur$处理后指标$R$。 

关键的实现细节是，步骤 3 可能看起来需要重复增量，但实际上每个增量只能“解决”每个索引的一个禁止匹配，因此总的来说，每个冲突都可以被计费一次。 

### 为什么它有效

 该算法保持每个索引处的不变式$i$,$cur$是使得前缀的最小可能值$B_L..B_i$有效且不减。 任何较小的值都会违反单调性或等于$A_i$。 由于较早增加只会使以后的约束变得更加困难，因此始终尽早解决冲突可确保最终值全局最小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []
    for _ in range(T):
        n, q = map(int, input().split())
        a = [0] + list(map(int, input().split()))

        for _ in range(q):
            l, r = map(int, input().split())
            cur = 1

            for i in range(l, r + 1):
                if cur == a[i]:
                    cur += 1
                # cur always stays non-decreasing, so no reset needed

            out.append(str(cur))

        print(" ".join(out[-q:]))

if __name__ == "__main__":
    solve()
```该解决方案通过模拟贪婪构造来处理每个查询。 变量`cur`代表当前选择的值$B$。 在每个索引处，如果它与$A_i$。 这直接强制执行两个约束：保证单调性，因为`cur`永远不会减少，并且通过跳过禁止值来强制执行不等式约束。 

一个微妙的点是索引：使用基于 1 的索引`a`简化了与查询范围的对齐，避免读取段时出现相差一的错误。

 ## 边缘情况

 当当前值重复匹配连续元素时，就会出现关键边缘情况$A$。 例如，如果$A = [1, 2, 3, 4]$我们从1开始，我们立即在第一个位置发生冲突，跳到2，然后再次发生冲突，并继续增加。 该算法自然地处理了这个问题，因为每次冲突都会触发一个增量，并且该值只会向前移动。 

另一种边缘情况是根本没有发生冲突，例如$A = [5, 6, 7]$。 从 1 开始，我们永远不会匹配任何值，因此答案仍然是 1。这证实了该算法不会过度递增并真正保留了极小性。 

第三个边缘情况是一个长平台，就像$A = [2, 2, 2, 2]$。 这里的值从 1 开始并且永远不会发生冲突，这表明禁止的约束是稀疏的，并且单调规则本身并不会强制增长。
