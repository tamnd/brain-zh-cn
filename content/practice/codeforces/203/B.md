 ## 解决方案
 ## 问题理解

 我们有一个`n × n`网格开始完全白色。 细胞被一个接一个地涂成黑色，每一次移动都会涂上不同的细胞。 每次移动后，我们想知道棋盘上是否已经包含一个全黑的棋子`3 × 3`正方形。 

任务是输出此类方块首次出现的最早移动索引。 如果没有`3 × 3`块变得全黑，我们打印`-1`。 

网格大小最多为`1000 × 1000`，这意味着电路板最多包含一百万个单元。 绘画操作次数最多为`10^5`。 这立即排除了任何在每次移动后重复扫描整个棋盘的方法。 重新检查所有可能的情况`3 × 3`每次平方大约需要：$$10^5 \times 10^6 = 10^{11}$$最坏情况下的操作，远远超出了极限。 

小的固定正方形尺寸是这里的关键细节。 我们并不是在寻找任意的矩形或大的图案。 每个有效的配置都是准确的`3 × 3`，因此每个新绘制的单元格只能影响附近极少数的候选方格。 

有一些容易被忽略的边缘情况。 

假设电路板太小，甚至无法容纳`3 × 3`正方形。 

输入：```
2 4
1 1
1 2
2 1
2 2
```正确输出：```
-1
```粗心的实现可能仍会尝试检查相邻位置并意外访问无效索引。 

当最终绘制的单元格不是已完成的正方形的左上角时，会出现另一种微妙的情况。 

输入：```
3 9
1 1
1 2
1 3
2 1
2 2
2 3
3 1
3 2
3 3
```正确输出：```
9
```如果我们只检查左上角等于新绘制的单元格的正方形，我们就完全错过了这一点。 最后一个动作是`(3,3)`，但相关的`3 × 3`正方形开始于`(1,1)`。 

还有一种情况是，几个`3 × 3`正方形重叠。 

输入：```
4 10
1 1
1 2
1 3
2 1
2 2
2 3
3 1
3 2
4 1
3 3
```正确输出：```
10
```该算法必须在任何有效方格存在的第一时刻停止，而不是在处理完所有移动之后停止。 

## 方法

 最直接的解决办法就是暴力破解。 每次移动后，我们都会扫描所有可能的情况`3 × 3`子网格并检查所有九个单元格是否都是黑色的。 

有`(n - 2)^2`候选方格，每次检查检查 9 个单元格。 复杂度变为：$$O(m \cdot n^2)$$为了`n = 1000`和`m = 10^5`，这变得太大了。 

重要的观察结果是，绘制一个单元格只会改变包含该单元格的方块。 由于目标方块大小固定为`3 × 3`，单个细胞最多属于9个不同的`3 × 3`正方形。 

例如，如果我们绘制细胞`(x, y)`，然后是任何受影响的左上角`3 × 3`正方形必须位于：$$(x-2 \dots x,\ y-2 \dots y)$$只有9种可能性。 棋盘上的所有其他方格保持不变，不需要再次检查。 

这将问题从重复扫描整个网格转变为在每次移动后仅检查恒定数量的本地配置。 

由此产生的复杂性与移动次数成线性关系。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(m·n²) | O(n²) | 太慢了 |
 | 最佳 | O(米) | O(n²) | 已接受 |

 ## 算法演练

 1. 创建一个`n × n`布尔网格初始化为`False`。 

每个单元存储它是否已经被漆成黑色。 
2. 按照输入顺序一一处理动作。 

创建有效的第一步`3 × 3`正方形就是答案，所以我们必须按顺序评估移动。 
3. 标记当前单元格`(x, y)`作为黑色。 
4. 枚举所有可能的左上角`3 × 3`可以包含的正方形`(x, y)`。 

这些角是：```
(x-2, y-2) ... (x, y)
```最多有 9 名候选人。 
5. 对于每个候选左上角`(r, c)`，首先验证正方形是否位于棋盘内。 

我们需要：```
0 ≤ r ≤ n-3
0 ≤ c ≤ n-3
```6. 检查里面的所有 9 个单元格`3 × 3`正方形。 

如果每个单元格都是黑色的，则立即打印当前的移动编号并终止。 
7. 如果所有移动完成后都没有找到有效的方块，则打印`-1`。 

### 为什么它有效

 一个`3 × 3`正方形只能在其单元格之一被绘制时改变状态。 涂漆前`(x, y)`，每个不受影响的方格都具有与之前完全相同的单元格，因此其有效性不会改变。 

这意味着移动后，唯一值得检查的方块是包含新绘制的单元格的方块。 由于每个这样的方块都会被明确地检查，因此算法不会错过第一个完成的方块`3 × 3`堵塞。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())

    grid = [[False] * n for _ in range(n)]

    for move in range(1, m + 1):
        x, y = map(int, input().split())
        x -= 1
        y -= 1

        grid[x][y] = True

        for r in range(x - 2, x + 1):
            for c in range(y - 2, y + 1):

                if r < 0 or c < 0 or r + 2 >= n or c + 2 >= n:
                    continue

                ok = True

                for i in range(r, r + 3):
                    for j in range(c, c + 3):
                        if not grid[i][j]:
                            ok = False
                            break

                    if not ok:
                        break

                if ok:
                    print(move)
                    return

    print(-1)

if __name__ == "__main__":
    main()
```该解决方案将棋盘存储为布尔矩阵。 使用布尔值可以使实现简单而高效，因为每次查找都变成直接数组访问。 

读取输入后，坐标立即转换为从零开始的索引。 这样就避免了重复`-1`稍后进行调整并使边界条件更容易推理。 

循环：```
for r in range(x - 2, x + 1):
    for c in range(y - 2, y + 1):
```列举所有可能的`3 × 3`正方形包含`(x, y)`。 一个常见的错误是只检查`(x, y)`作为左上角，它错过了许多有效的配置。 

边界测试：```
if r < 0 or c < 0 or r + 2 >= n or c + 2 >= n:
```防止板边缘附近的无效索引。 

嵌套循环`3 × 3`一旦发现一个白细胞，该区域就会提前停止。 这使得常数因子保持较小。 

一旦出现有效方块，程序就会打印移动索引并立即退出。 由于移动是按时间顺序处理的，因此第一个检测到的方格保证是最早的方格。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(米) | 每次移动最多检查 9 个候选方格，每个方格包含 9 个方格 |
 | 空间| O(n²) | 板状态显式存储 |

 每次移动的最大工作量受一个小常数的限制。 即使是为了`10^5`移动时，单元检查总数仍然在时间限制内。 内存使用也是安全的，因为`1000 × 1000`布尔网格可以轻松容纳在 256 MB 内。
