 ## 解决方案
 ## 问题理解

 比赛期间有两个独立的任务可供使用，比赛时间从 0 分钟到 t - 1 分钟。每个任务的分数随时间线性下降。 如果您在第 i 分钟解决第一个任务，您将收到一个负 i 乘以从初始 a 中减去 da 点的结果。 第二个任务的行为与初始值 b 类似，并且每分钟递减 db。 

参赛者可以跳过任务或仅解决一次任务，并且每次解决都必须在比赛窗口内的某个整数分钟内发生。 总分是所有已解决任务在选定时间的值的总和。 问题是是否有可能恰好获得x个总分。 

关键在于时间仅独立影响每个任务的价值，并且只有两个任务，因此任何解决方案都完全通过为每个任务选择时间或选择不解决来确定。 

约束足够小，即使对所有时间选择进行二次推理也是可行的。 t 的最大值为 300，因此检查所有分钟对最多可达 90,000 个组合，这完全在限制范围内。 即使是效率稍低的方法也会很容易通过。 

一个微妙的点是，稍后解决任务总是会减少其贡献，但不会因为声明中的保证而使其变得消极。 这可以防止任何涉及负分或需要考虑无效提交的边缘情况。 

当 x 为零、仅需要一项任务或需要两项任务时，就会出现边缘情况。 一个天真的错误是假设您必须始终解决这两项任务，这会错误地拒绝诸如 x 等于 a 或 x 单独等于 b 之类的情况。 例如，如果 x 等于 a 并且 b 很大但没有必要，则通过仅在时间 0 解决第一个任务，正确答案仍然可以是“是”。 

另一个极端情况是两项任务必须在不同时间解决。 粗心的方法可能会假设两者都必须在时间 0 处解决才能最大化得分，但问题不在于最大化，而在于匹配精确值，这可能需要延迟一项任务以减少其贡献。 

## 方法

 如果我们忽略效率问题，最直接的想法是尝试所有可能的决定：跳过这两项任务，在任何有效分钟仅执行第一个任务，在任何有效分钟仅执行第二个任务，或者在 i 和 j 分钟的某种选择下执行两项任务。 由于每个任务都可以独立调度，因此这成为所有时间对的完整枚举。 

这个暴力视图检查 [0, t-1] 中的所有 i 和 [0, t-1] 中的所有 j，计算执行两个任务时所得分数的总和。 我们还隐式地包含了通过将一项任务视为“未选择”来跳过该任务的情况。 正确性很简单，因为每个有效策略恰好对应于一对 (i, j) 或一个缺失的选择。 

总对数最多为 300 × 300，即 90,000 次评估。 每次评估都是恒定时间，因此暴力破解已经完全符合时间限制。 然而，我们可以通过分离这两个任务来进一步简化结构。 

对于每个可能的时间 i，我们可以计算第一个任务的分数。 对于每个可能的时间 j，我们计算第二个任务的分数。 那么问题就变成检查这两个集合中是否存在一对值之和为 x。 这是小数组上的经典二和，可以用线性时间内的哈希集来解决。 

我们可以将第二个任务的所有可能值预先计算到一个集合中，然后迭代第一个任务的所有可能值，检查集合中是否存在 x 减去该值。 这降低了概念复杂性，同时保持相同的最坏情况性能。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解所有 (i, j) | O(t²) | O(1) | O(1) | 已接受 |
 | 预计算+哈希集| O(t) | O(t) | 已接受 |

 ## 算法演练

 1. 通过将 i 分钟从 0 迭代到 t 负 1 并计算 a 负 i 乘以 da，构建第一个问题的所有可能分数。 这捕获了解决第一个任务的所有有效方法。 
2. 类似地，通过将​​ j 分钟从 0 迭代到 t 减 1 并计算 b 减 j 乘以 db，为第二个问题建立所有可能的分数。 这给出了第二个任务的全套可实现的贡献。 
3. 将所有第二任务分数插入哈希集中，以便可以在恒定时间内完成成员资格查询。 这就是以后可以快速配对的原因。 
4. 迭代每个第一个任务的得分。 对于每个值 s1，计算所需的补值 x 减去 s1。 
5. 检查第二任务集中是否存在该互补值。 如果确实如此，我们就找到了两个提交时间的有效组合，恰好产生 x，因此我们可以立即停止。 
6. 如果在用尽所有第一个任务值后没有组合有效，则得出 x 无法形成的结论。 

它为何有效取决于每个任务独立贡献且最多一次的事实。 每个有效的竞赛结果都对应于从第一组中选择一个值并从第二组中选择一个值（或者通过有效地不选择任何元素来跳过）。 由于所有这些值都已枚举，因此检查所有总和涵盖了所有可能的策略，没有遗漏或重复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x, t, a, b, da, db = map(int, input().split())

    A = []
    for i in range(t):
        A.append(a - i * da)

    Bset = set()
    for j in range(t):
        Bset.add(b - j * db)

    for v in A:
        if x - v in Bset:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```第一个循环在每个有效分钟内构建解决第一个问题的所有可能分数。 第二个循环将第二个问题的所有可能分数存储在哈希集中，从而实现补集的恒定时间查找。 最后一个循环尝试每个第一个任务值，并检查是否可以通过某些第二个任务计时来实现剩余的所需分数。 

一个微妙的点是，跳过问题是隐式处理的：由于问题保证非负分数，有效选择总是对应于选择某个分钟，并且零贡献情况不需要作为显式选项。 

## 工作示例

 ### 示例 1

 输入：```

```我们计算可能的值：

 第一个任务值：20、17、14、11、8

 第二个任务值：20、15、10、5、0

 | 第一个值 | 所需的第二个值（x - 第一个）| 存在于第二组 |
 | --- | --- | --- |
 | 20 | 10 | 10 是的 |

 在第一次成功匹配时，20 + 10 等于 30，所以答案是 YES。 

该轨迹表明我们不需要探索所有对，只需找到一个有效的分解即可。 

### 示例 2

 输入：```

```第一个任务值：10、8、6

 第二个任务值：12、9、6

 | 第一个值 | 所需的第二个值 | 存在 |

 | 8 | 17 | 17 没有 |

 没有配对产生 25，所以答案是否定的。 

此案例表明，即使存在单个值，不匹配的组合也可能完全失败。

 ## 边缘情况

 当 x 等于 0 时，成功的唯一方法是避免以总和为零的方式贡献正值。 由于所有生成的值都是非负的，因此仅当存在产生零的有效组合时才有效。 该算法自然会处理这个问题，因为它仍然检查所有对，并且如果两个集合在某个时间都包含零，则总和是匹配的。 

当只需要一项任务时，正确的解决方案是将一组值与另一组的隐式零贡献配对。 在本实施例中，跳过是指不需要进行第二次选择； 但是，由于这些集合包含基于时间的值，因此当其他任务提供正确补充 x 的值时，任何有效的单任务解决方案都会直接显示为匹配项。 

当两个任务都具有较大的初始值但较大的减量时，稍后可能会产生非常小的贡献或零贡献。 枚举正确地包括了这些情况，因为每一分钟都是独立测试的，确保不会错过任何有效的后期解决方案。
