 ## 解决方案
 ## 问题理解

 每个客户都会描述 Valera 必须执行的固定工作量：一定数量的低质量照片和一定数量的高质量照片。 每张低质量照片都会消耗固定数量的相机内存，而每张高质量照片都会消耗（可能更大）固定数量。 照片一旦拍摄，就会永久占用内存，因此可用空间只会随着时间的推移而减少。 

对于任何客户，如果瓦莱拉同意为他们提供服务，他必须提供所有要求的照片，并且这些照片使用的内存将添加到相机中。 目标不是在连续意义上最大化总照片或内存使用效率，而只是选择可以顺序服务的客户端子集，而总内存使用量不会超过相机容量。 

关键是顺序不会以有意义的方式改变可行性。 由于内存只会被消耗而不会被释放，因此以任何顺序为客户端提供服务都会导致相同的总内存使用量，这只是所选客户端上所有照片的总和乘以各自的成本。 

对于多达 100,000 个客户端，任何尝试所有子集的解决方案都是不可能的，因为它需要指数时间。 即使检查所有排列也远远超出了可行的限制。 围绕 O(n log n) 或 O(n) 的解决方案是必要的，因为典型的竞争性编程约束允许在两秒内执行大约 10^8 个简单操作。 

当仅基于一种类型的照片应用贪婪的想法时，会出现微妙的边缘情况。 例如，如果仅考虑一个参数，则拥有许多低质量照片但没有高质量照片的客户可能看起来更便宜。 然而，正确的成本同时取决于这两种类型。 

考虑这个输入：```
2 10
2 3
1 4
3 1
```客户 1 的成本为 1·2 + 4·3 = 14，客户 2 的成本为 3·2 + 1·3 = 9。尽管客户 1 的照片总数较少，但只能拍摄客户 2。 如果忽略权重，按请求数量排序的幼稚策略可能会错误地选择。 

## 方法

 暴力方法是尝试客户端的每个子集，计算每个子集所需的总内存，并保留最大的有效内存。 这是正确的，因为它明确地检查了所有可能性。 然而，子集的数量为 2ⁿ，即使 n = 30，这也已经超过了 10 亿种可能性，使其在达到问题约束之前很久就无法使用。 

关键的观察是，一旦选择了一个客户端，他们的整个内存需求就是固定的并且独立于其他客户端。 除了通过全局总和之外，客户端之间没有任何交互。 这将问题转化为选择具有权重的项目，其中每个客户端的权重等于他们消耗的总内存。 

一旦简化为这种形式，问题就变成了经典的优化任务：在总重量限制下最大化所选物品的数量。 最佳策略是首先优先选择总内存成本较小的客户端。 任何增加订单的偏差都会用较重的客户端取代较轻的客户端，从而减少剩余容量中可容纳的客户端数量。 

按总成本对客户进行排序，并贪婪地对待他们，直到下一个不适合为止，从而产生最佳解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2ⁿ·n) | O(2ⁿ·n) | O(n) | 太慢了 |
 | 最优贪心排序 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算每个客户端的内存成本：ci = xi · a + yi · b。 这可以捕获客户端消耗的确切内存量，因为每张照片都会独立地添加固定的内存使用量。 
2. 将每个计算的成本与客户端索引配对，这样我们在排序后就不会丢失身份。 
3. 按非降序排列所有客户的成本。 直觉是，首先为更便宜的客户提供服务，为其他客户留下更多的剩余容量。 
4. 迭代排序列表，维护已用内存的运行总和以及选定的客户端集。 
5. 对于每个客户端，检查添加其成本是否使总内存保持在限制 d 内。 如果是，请包括客户端并更新总和。 如果不是，请停止处理更多客户，因为所有剩余的客户至少同样昂贵。 

提前停止是有效的，因为排序保证了每个后续客户端的成本都大于或等于当前客户端，因此如果当前客户端不适合，那么接下来的客户端也不会适合。 

### 为什么它有效

 该算法保持了这样的不变性：在所有已处理的客户中，我们总是首先选择最便宜的可用客户。 假设存在一种更好的解决方案，可以接受更昂贵的客户，同时跳过更便宜的客户。 交换它们不会增加总内存使用量，也永远不会减少占用的客户端数量，这与最优性相矛盾。 这个交换论证保证了任何最优解都可以无损失地转化为贪心解，因此贪心构造是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, d = map(int, input().split())
a, b = map(int, input().split())

clients = []
for i in range(n):
    x, y = map(int, input().split())
    cost = x * a + y * b
    clients.append((cost, i + 1))

clients.sort()

total = 0
ans = []

for cost, idx in clients:
    if total + cost <= d:
        total += cost
        ans.append(idx)
    else:
        break

print(len(ans))
print(*ans)
```其实现直接反映了贪婪策略。 每个客户端完成的唯一计算是将其请求转换为单个标量成本。 排序确保我们始终首先考虑最小的剩余成本。 

一个微妙的细节是提前休息。 它是安全的，因为数组是按成本排序的，所以一旦某个客户端不适合，后面的客户端就无法在剩余容量下容纳。

## 边缘情况

 一种重要的边缘情况是所有客户端都单独超出了容量。 该算法对它们进行排序，但立即发现第一个不适合，因此它正确输出零个客户端，而无需尝试进一步添加。 

另一种情况是多个客户具有相同的成本。 排序使它们保持相邻，并且算法将选择尽可能多的合适的。 由于所有的权重相同，因此最大大小的任何子集都是有效的。 

最后一种情况是当一个非常大的客户出现在许多小客户中时。 贪婪方法自然会避开大客户，除非它在排序顺序中出现在较小客户之前，但由于排序是按成本排序，因此它总是放在最后，确保首先对较小客户进行最佳选择。
