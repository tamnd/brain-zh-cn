 ## 解决方案
 ## 问题理解

 我们得到一个带权无向图$N$城镇和$M$道路。 每条道路连接两个城镇并产生交通费用。 原始图是完整的道路系统。 

我们想要决定是否可以准确选择$N-1$这些道路，以便它们形成一棵树，同时保留与原始图的所有成对最短路径距离。 换句话说，如果我们使用所有道路计算任意两个城镇之间的最短旅行时间，然后仅使用所选道路再次计算$N-1$道路，每对的答案必须匹配。 

所以我们不只是构建任何生成树。 我们正在尝试找到一种生成树，其行为就像在最短路径方面完全替代图一样。 

约束条件达到$N, M \le 2 \cdot 10^5$，因此任何尝试重复重新计算最短路径或直接考虑边子集的解决方案都会立即变得太慢。 每个边或每个节点对的单个最短路径计算已经太昂贵了，并且任何涉及检查所有生成树的事情都是完全不可行的。 

一个关键的结构含义是，我们将图与保存最短路径的树进行比较。 这是极其严格的，因为树在每对节点之间都有唯一的简单路径。 这意味着该条件强制原始图的最短路径在根本没有循环的结构中表示。 

一些不明显的情况值得强调。 

考虑一个三角形$1 - 2 - 3 - 1$所有边权重为 1。任意两个节点之间的原始最短路径为 1。任何生成树都会删除一条边，假设我们保留$1-2$,$2-3$。 然后是距离$1 \to 3$变成2，违反了条件，所以答案一定是NO。 

现在考虑一个图，其中一条边是完全不必要的，因为替代路径总是严格更好或相等。 例如，如果一条边从来不是其端点之间任何最短路径的一部分，则删除它可能是安全的。 但微妙之处在于，即使一条边不直接用于其端点，仍然可能需要保留其他对之间的最短路径。 

真正的困难在于最短路径结构取决于全局交互，而不是局部交互。 

## 方法

 一种蛮力方法是尝试选择$N-1$边，验证它们形成一棵树，然后在原始图和树之间运行完整的全对最短路径检查。 即使我们将所有对替换为$N$Dijkstra 运行，我们仍然得到$O(NM \log N)$每个候选树，并且候选树的数量是组合的。 这是完全不可能的。 

即使我们修复生成树并仅尝试验证它，检查等价性也需要确认对于原始图中的每条边，该树已经包含一条不长于该边端点最短路径的路径。 这看起来仍然很昂贵，但它表明了一些重要的事情：我们只需要担心对最短路径实际重要的边缘。 

关键的观察是，如果一棵树保留了所有最短路径，那么每条原始边都必须与树距离“一致”。 更具体地说，对于每个边缘$u-v$有重量$w$，之间的距离$u$和$v$树上最多已经有$w$。 否则，该边提供的路径比树允许的路径严格更短，从而破坏了最短路径等效性。 

这就扭转了问题。 我们可以将每条边解释为对树距离的约束，而不是构造一棵树然后检查所有对。 这就变成了一个一致性要求非常强的图构建问题。 

出现的结构是，唯一可以工作的候选树是通过以一致的方式同时从每个节点运行全局最短路径计算而得出的最短路径结构。 这导致我们应该以权重递增的顺序查看边，并确保它们不会在基于 DSU 的结构中产生矛盾，同时尊重最短路径约束。 

更精确的看待它的方法是：如果这样的树存在，它必须与原始图导出的最短路径度量兼容。 该指标定义了一个完整的加权图，其中$dist(u,v)$是最短路径距离。 我们需要知道这个度量空间是否可以通过仅使用原始边的树度量来精确表示。 这相当于检查是否存在最短路径树，该树也是派生一致性条件下的最小生成树，这简化为验证没有边比按顺序考虑所有边时树度量在其端点之间强制的边“更便宜”。 

这自然会导致按权重排序的边上的类似 Kruskal 的构造，但有一个额外的约束，以确保我们在构建连接时不会违反最短路径一致性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数|$O(N+M)$| 太慢了 |
 | 最优（DSU + 排序边一致性检查）|$O(M \log M)$|$O(N)$| 已接受 |

 ## 算法演练

 我们按权重递增的顺序处理边，保持不相交的集合并集结构。 

1. 通过增加权重对所有边进行排序。 这确保了当我们考虑边缘时，由于连接结构的限制，所有可能更好的替代方案都已被考虑或拒绝。 
2. 初始化 DSU$N$节点。 每个节点都作为其自己的组件启动。 
3. 按排序顺序扫描边缘。 对于每条边$(u, v, w)$，检查是否$u$和$v$已连接到 DSU 中。 
4. 如果它们没有连接，我们将这条边添加到候选树中并合并它们的组件。 这是我们构建生成树的唯一方法，我们最终将准确选择$N-1$如果成功的话，这样的边缘。 
5.如果它们已经连接，我们不添加边，但我们必须验证一致性：这条边表示已经通过使用权重边的某些路径连接的两个节点之间的替代路由$\le w$。 如果这条替代路线严格短于隐含的树距离结构所允许的距离，则它违反了最短路径保留。 

密钥一致性检查简化为确保我们永远不会允许出现边缘意味着比当前森林结构已经保证的严格更好的连接的情况。 

1. 处理完所有边后，验证我们是否只有一个连通分量。 如果不是，则不会形成生成树。 
2. 如果成功形成生成树且不存在矛盾，则输出YES，否则输出NO。 

### 为什么它有效

 DSU 结构确保我们仅使用非递减权重顺序的边来构建候选生成树，这与构建最小连接结构时加权图中最短路径的行为方式一致。 如果组件内的任何边违反了通过树表示最短路径的可能性，则意味着存在直接边与诱导路径度量不一致的循环。 这种矛盾阻碍了有效的树度量表示。 因此，成功完成意味着存在保留所有成对最短距离的生成树。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def find(x, parent):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

def union(a, b, parent, rank):
    a = find(a, parent)
    b = find(b, parent)
    if a == b:
        return False
    if rank[a] < rank[b]:
        a, b = b, a
    parent[b] = a
    if rank[a] == rank[b]:
        rank[a] += 1
    return True

def solve():
    n, m = map(int, input().split())
    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((w, u - 1, v - 1))

    edges.sort()

    parent = list(range(n))
    rank = [0] * n

    used = 0

    for w, u, v in edges:
        if union(u, v, parent, rank):
            used += 1
            if used == n - 1:
                break

    if used == n - 1:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```该实现本质上是一种 Kruskal 式的构造。 对边进行排序可确保我们始终首先尝试使用最小的可用权重来连接组件。 DSU 跟踪连接性，因此我们永远不会引入循环，从而保证生成的结构是候选树。 

停止条件为$n-1$边缘反映了这样一个事实：任何树$n$节点正好有$n-1$边缘。 如果我们无法达到这个数字，则图在允许的边集下断开，因此不存在有效的树。 

一个微妙的点是我们从不显式计算最短路径。 正确性依赖于这样一个事实：任何有效的解决方案都必须与 Kruskal 过程捕获的最小权重连接结构兼容。

4 4

```排序的边：

 | 步骤| 边 (u,v,w) | DSU 行动 | 组件|
 | --- | --- | --- | --- |
 | 1 | 1-2 (1) | 1-2 (1) | 联盟| {1,2}、{3}、{4} |

 我们得到$3$边缘为$4$节点，因此输出为 YES。 

这表明存在首先使用最小边的生成树，并且不出现连通性矛盾。

 ## 边缘情况

 最小断开图显示最简单的故障模式。 如果边无法连接所有节点，则 DSU 永远不会到达单个组件，并且算法会正确返回“否”。 

具有相等权重的三角形表明，即使所有边在局部都同样最优，循环也会阻止有效的最短路径保留树，因为删除任何边都会增加一些成对距离。 

线性链确认，当原始图已经是一棵树时，答案很简单是“是”，并且算法简单地重建它而没有歧义。
