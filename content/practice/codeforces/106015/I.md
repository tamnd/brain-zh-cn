 ## 解决方案
 ## 问题理解

 我们得到一个图，其中交叉路口是节点，街道是无向边。 每条边都有一个以百分比表示的成功概率，这意味着如果您穿过那条街道，您将以该概率生存，并以互补的风险失败。 从节点 1 到节点 n 的完整路径的总成功概率等于沿该路径的边概率的乘积。 

还有一个额外的变化：在开始之前，我们可以精确地选择一个边缘并将其升级到 100% 的成功概率。 这意味着无论其原始值如何，其乘数都会变为 1.0。 目标是选择从节点 1 到节点 n 的路径，并决定升级该路径上的哪条边，以使所得概率乘积最大化。 

该图最多可以有 100000 个节点和 200000 条边。 这立即排除了任何尝试枚举路径的解决方案。 即使对所有简单路径进行最短路径样式枚举也是不可能的，因为密集图中的路径数量呈指数增长。 我们也无法承受超出线性或接近线性复杂度的每条边的重复昂贵的状态扩展，因此解决方案必须将问题减少到少量的图遍历。 

一个微妙的问题是概率是乘法的并且涉及浮点精度。 另一个微妙之处是，升级的最佳边缘取决于路径本身，因此我们不能在没有全局信息的情况下贪婪地决定升级。 

一个天真的但常见的错误是忽略升级并只计算最佳概率路径。 当低概率边缘不可避免但可以被抵消的情况下，这种方法会失败。 

例如，考虑链 1-2-3，其中边为 50% 和 50%。 如果不升级的话，答案是 25%。 但升级任一边缘都会使总数达到 50%，因此简单的解决方案将输出 25%，而不是 50%。 

另一个陷阱是假设我们应该始终升级全局的最小边缘。 但这会失败，因为最佳候选者取决于哪些边位于最佳路径上。 

## 方法

 关键的挑战是我们正在沿着一条路径优化产品，并将一个可选的乘法提升应用于单个边缘。 如果我们忽略提升，问题就变成了图中经典的最大概率路径，可以通过 Dijkstra 对数或直接最大化乘积来解决。 

让我们从这个基线开始。 如果我们为每条边定义一个标准权重作为其概率，那么从 1 到 n 的最佳路径就是最大化概率乘积的路径。 这可以使用修改后的 Dijkstra 来计算，其中距离相乘而不是相加。 这是可行的，因为所有概率都是正的且独立的，因此最优子结构成立。 

然而，这只是给我们提供了没有升级的最佳路径。 升级改变了结构：沿着选定的路径，一条边变成 1.0 而不是 p/100。 如果我们修复一条路径，则升级的最佳边缘显然是该路径上的最小概率边缘，因为替换最小乘数会产生最大的相对增益。 因此，对于固定路径，最佳可实现值是所有边除以该路径上的最小边概率的乘积。 

因此，问题就变成了找到一条最大化乘积除以其最小边权重的路径。 

这转化为二维优化：我们想要一条在总产品上同时强大且具有尽可能大的薄弱环节的路径。 诀窍是将其重新解释为扩展状态空间中的最短路径。

我们为每个节点定义两种状态：一种是我们尚未使用升级，另一种是我们已经使用过升级。 从状态（节点，未使用），遍历一条边有两个选择：要么我们不使用升级并乘以它的概率，要么我们在这条边上使用升级并乘以1。从状态（节点，已使用），我们必须像往常一样乘以概率。 这是具有 2n 个状态的标准分层 Dijkstra。 

这是有效的，因为升级哪条边的决定被推迟到遍历时间，并且所有可能性都被探索一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解所有路径 | 指数| O(n) | 太慢了 |
 | 2 状态 Dijkstra | O(m log n) | O(n + m) | 已接受 |

 ## 算法演练

 我们运行最大概率 Dijkstra，但将每个节点复制到两层中，表示升级是否已被使用。 

1. 我们初始化一个优先级队列，其中每个条目存储（到目前为止的概率、节点、used_flag）。 我们从节点 1 开始，概率为 1，used_flag = 0。这表示我们尚未应用保证安全边缘。 
2. 我们维护一个距离数组 dist[node][used_flag] 存储达到该状态的最佳已知概率。 除起始状态外，所有值均从 0 开始。 
3. 当优先级队列不为空时，我们提取概率最高的状态。 这确保了我们总是首先扩展最有希望的部分路径，这是 Dijkstra 的乘法模拟。 
4. 对于每个传出边 (u, v, p)，我们根据used_flag 考虑转换。 

如果used_flag为0，我们有两种选择。 我们可以正常遍历，以 current * p 的概率更新状态 0 中的 v，或者我们可以在这条边上使用升级并以 current * 1 的概率移动到状态 1。第二个转换是边变得保证安全的唯一时刻。 

如果used_flag为1，我们必须正常遍历，以current * p的概率移动到状态1。 
5. 每当我们计算一个状态的新概率时，如果它比存储的值更好，我们就会更新它，并将其推入优先级队列。 
6. 答案是 dist[n][0] 和 dist[n][1] 中的最大值，因为在到达目的地时我们可能已经或可能没有使用升级。 

### 为什么它有效

 关键的不变量是每个状态代表到达具有固定升级使用状态的节点的最佳可能概率。 由于每次转换都会将概率乘以固定的正因子，因此最佳路径的任何前缀对于其端点状态也是最佳的。 优先级队列确保状态按照概率递减的顺序进行处理，因此一旦状态被弹出，以后的松弛就无法改善它。 复制到两层中可以正确编码一次性约束，而不会丢失任何全局最优决策。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v, p = map(int, input().split())
        prob = p / 100.0
        g[u].append((v, prob))
        g[v].append((u, prob))

    dist = [[0.0, 0.0] for _ in range(n + 1)]
    dist[1][0] = 1.0

    pq = [(-1.0, 1, 0)]

    while pq:
        neg_cur, u, used = heapq.heappop(pq)
        cur = -neg_cur

        if cur < dist[u][used]:
            continue

        for v, w in g[u]:
            # not using upgrade
            nxt = cur * w
            if nxt > dist[v][used]:
                dist[v][used] = nxt
                heapq.heappush(pq, (-nxt, v, used))

            # use upgrade if not used yet
            if used == 0:
                nxt2 = cur * 1.0
                if nxt2 > dist[v][1]:
                    dist[v][1] = nxt2
                    heapq.heappush(pq, (-nxt2, v, 1))

    ans = max(dist[n][0], dist[n][1])
    print(f"{ans * 100:.6f}")

if __name__ == "__main__":
    solve()
```该图构建为邻接列表，其中概率转换为浮点乘数。 距离表存储每个节点在两种状态下的最佳概率。 优先级队列使用负值来模拟最大堆。 

关键的微妙之处在于尚未使用升级时的拆分过渡。 我们明确允许将其“花费”在任何遍历的边缘上，这与沿着最终路径选择最佳边缘完全对应。 

最终答案乘以 100 以转换回百分比格式。

 ## 边缘情况

 1 和 n 之间的直接边是最简单的应力情况。 用于输入`1 2 30`，该算法考虑两种状态：使用升级立即给出 1.0，这是正确选择的。 

具有多个平行边的图测试算法是否错误地假设了边的唯一性。 由于在转换中独立考虑每条边，因此始终选择最佳的 100% 升级。 

低概率的长链测试积累。 如果不升级，概率就会成倍下降。 该算法正确地将升级应用于链上最有影响力的边，因为每条边在遍历时都是合格的。 

短路径概率较低但长路径结构较高的分割图测试全局最优性。 两层 Dijkstra 确保两条路径的评估一致，并且无论路由长度如何，都会选择最佳端点状态。
