 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 每一个都有一个整数数组，我们必须根据两个值的最小公倍数计算有多少对索引产生特殊条件。 

如果一对位置的值的 LCM 具有非常特定的结构，则它们对答案有贡献：在其分解中出现的每个素数必须以至少 2 的指数出现。 换句话说，LCM 不能只包含任何质数的一次方。 如果素数整除 LCM，则它必须至少除以它的平方。 

输入大小立即迫使我们远离每个测试用例的任何二次方。 所有测试用例中的元素总数最多为 200000，因此任何尝试显式检查每个测试用例中所有对的解决方案都会超时。 在最坏的情况下，简单的 O(N²) 扫描将执行大约 1010 次操作，这远远超出了 2 秒允许的范围。 

如果试图仅对单个元素进行推理，就会出现一种微妙的故障模式。 例如，像 6 (2·3) 或 10 (2·5) 这样的数字看起来“简单”，但将其与另一个数字组合可以将仅出现一次的素数引入 LCM 中。 条件不是关于单个数字是否“满方”，而是关于 LCM 中合并的素数结构。 

当数字共享素数但指数不同时，就会出现另一种边缘情况。 例如，4 (2²) 和 2 (21) 产生的 LCM 为 4，这是有效的，但 4 和 8 产生 8，这是无效的，因为 2³ 包含素数指数 3，但由于 3 ≥ 2，这仍然没问题。当素数在 LCM 中只出现一次时，真正的失败就会出现，只有当两个数字都在指数 1 上贡献它时，才会发生这种情况。 

因此，问题简化为计算对，其组合素数行为永远不会在 LCM 中留下“单个指数”。 

## 方法

 蛮力方法很简单：迭代所有对，计算 LCM，将其因式分解，并检查每个质数指数是否至少为 2。 即使 LCM 计算速度很快，但每对的因式分解却不是。 当 N 达到 10⁵ 时，在最坏的情况下这会变成大约 10^10 对检查，每个检查都具有重要的算术。 这是不可行的。 

关键的观察结果是，该条件仅取决于 LCM 中是否出现指数恰好为 1 的素数。 对于给定的素数 p，当一个数字贡献 p1 而另一个数字贡献 p⁰ 或 p1 时，这种情况就会发生，使得该对中的最大指数恰好为 1。 这意味着这两个数字必须避免引入“孤独”的素数指数。 

我们没有直接用 LCM 来思考，而是翻转了视角：​​通过无平方核对每个数字进行分类，但只关心在因式分解中出现的指数恰好为 1 的素数。 指数≥2 出现的素数是无害的，因为它们在 LCM 中已经单独满足条件。 

因此，我们可以将每个数字压缩为仅在其中出现一次的素数集合。 称其为“糟糕的签名”。 现在条件变成：对于一个好的数字对，它们的坏签名的对称差中必须不存在素数。 同样，两个数字必须具有相同的错误签名，因为任何不匹配都会创建一个素数，该素数恰好出现在指数 1 处的一个数字中，从而在 LCM 中成为指数 1。 

因此，任务简化为通过此签名对数字进行分组并计算每个组内的对。 

我们对每个数字计算其素数分解并提取指数恰好为 1 的素数。 我们将其编码为规范表示（例如，排序元组或冻结集）。 然后我们计算每个桶内的频率并求和组合。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N²√A)| O(1) | O(1) | 太慢了 |
 | 最佳 | O(N √A + N log N) | O(N √A + N log N) | O(N) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 对于每个数字，将其分解为素数并记录每个素数的指数。 我们只需要最多 10⁶ 的素数，因此试除最多 √A 或预先计算的基于筛的 SPF 数组就足够了。 这里的目的是提取精确的指数信息，而不仅仅是素数。 
2. 对于每个数字，构建一个由指数恰好为 1 的素数组成的“签名”。 指数为 2 或以上的素数将被忽略，因为它们不会在任何 LCM 配对中产生单例贡献。 
3. 将此签名转换为可散列表示形式。 素数的排序元组之所以有效，是因为顺序并不重要，但必须保留同一性。 
4. 维护从签名到拥有该签名的人数计数的频率图。 每组代表在生成指数一素数方面表现相同的数字。 
5. 对于每个大小为 k 的组，将 k·(k−1)/2 添加到答案中。 这会计算签名完全匹配的所有对，这意味着只有一个指数为 1 的数字中没有素数出现。 

分组起作用的原因是两个签名之间的任何不匹配都会引入至少一个其指数恰好为一的素数。 该素数在 LCM 中变成指数 1，违反了条件。 

### 为什么它有效

 该算法依赖于结构等价：当且仅当两个数字具有在因式分解中仅出现一次的相同素数集时，LCM 才没有指数一素数。 任何偏差都会引入一个素数，该素数会以指数 1 的形式保留到 LCM 中。 因此，有效对正是在相同签名类中形成的对，并且计数变成了频率上的简单组合聚合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXA = 10**6

# Precompute smallest prime factor
spf = list(range(MAXA + 1))
for i in range(2, int(MAXA ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXA + 1, i):
            if spf[j] == j:
                spf[j] = i

def factor_signature(x):
    sig = []
    while x > 1:
        p = spf[x]
        cnt = 0
        while x % p == 0:
            x //= p
            cnt += 1
        if cnt == 1:
            sig.append(p)
    return tuple(sig)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        freq = {}
        for _ in range(n):
            x = int(input())
            sig = factor_signature(x)
            freq[sig] = freq.get(sig, 0) + 1

        ans = 0
        for k in freq.values():
            ans += k * (k - 1) // 2
        print(ans)

if __name__ == "__main__":
    solve()
```筛子构建最小的质因数，因此每个数字都可以相对于其值以对数时间分解。 这`factor_signature`函数仅提取指数恰好为 1 的素数并将它们存储在元组中。 该元组用作字典键来对相同的行为进行分组。 

最后的循环使用标准 k 选择 2 公式对每个组内的配对组合进行计数。 

## 工作示例

 考虑一个小案例：`[6, 10, 15]`。 

| 数量 | 因式分解 | 签名|
 | --- | --- | --- |
 | 6 | 2^·3^| (2, 3) |
 | 10 | 10 2^·5^| (2, 5) |
 | 15 | 15 3^·5^| (3, 5) |

 所有签名都不同，因此不会计算任何对。 

这表明，尽管所有数字在结构上都“相似”，但任何配对都会引入不匹配素数，该素数在 LCM 中会变成指数 1。 

现在考虑`[4, 8, 9, 16]`。 

| 数量 | 因式分解 | 签名|
 | --- | --- | --- |
 | 4 | 2²| ()|
 | 8 | 2立方| ()|
 | 9 | 3²| ()|
 | 16 | 16 2⁴| ()|

 所有签名都是空的，因此所有对都是有效的。 该表显示指数 ≥2 的素数对签名没有贡献，因此所有数字都归为一组。 每对都被计算在内。

 ## 边缘情况

 一个关键的边缘情况是当数字都是全平方时，例如`[4, 8, 16]`。 每个签名都变成空，因此算法将所有内容组合在一起，并将所有对正确计数为 k·(k−1)/2。 幼稚的实现可能会错误地尝试直接检查 LCM 结构，并错过在这种情况下指数行为完全消失的情况。 

另一个边缘情况是每个数字都是不同素数的乘积，例如`[6, 10, 15]`。 每个签名都是唯一的，因此不存在配对。 该算法正确地将每个数字隔离到其自己的组中，避免了如果仅检查 gcd 或整除性而不是精确的指数一结构时可能出现的误报。
