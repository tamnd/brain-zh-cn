 ## 解决方案
 ## 问题理解

 我们得到了 N 块神奇苔藓的集合，每块苔藓在灯笼中使用后都会贡献固定的发光时间。 灯笼以简单的线性方式使用：每个苔藓片都被完全消耗，一个接一个，灯笼保持点亮的总时间恰好是所有单独燃烧持续时间的总和。 

输入由单个整数 N 后跟 N 个整数组成，其中每个整数代表特定的苔藓片可以让灯笼燃烧多长时间。 任务是计算使用所有部件时的总组合燃烧时间。 

从约束角度来看，N最多为1000，每次燃烧时间可以大到10^9。 这立即意味着对数组进行简单的线性传递就足够了。 即使在严格的 1 秒限制下，执行 1000 次加法也可以忽略不计，因此任何扫描列表一次并累加总和的解决方案都是最佳的。 

唯一微妙的问题是总和可能会变大。 如果有 1000 个值，每个值最大为 10^9，则总数可以达到 10^12，这超出了 32 位整数限制。 任何以 32 位类型存储结果的实现都会在重要的语言中悄悄溢出。 在 Python 中这不是问题，但在其他语言中这是一个典型的隐藏陷阱。 

边缘情况很少，但仍然值得具体说明。 如果 N = 1，则答案就是该单个值。 如果所有 Hi 均为 10^9，则总和为 10^12，并且仍必须正确打印。 如果所有值都相同，则结果应反映乘以 N，而不是任何形式的重复重置或部分累加错误。 

## 方法

 该问题的直接解释是通过迭代所有苔藓碎片并累积其燃烧时间来模拟灯笼的使用过程。 这种蛮力方法已经与所描述的过程相匹配：按顺序取出每个部分，将其持续时间添加到运行总数中，然后继续，直到所有部分都被消耗掉。 

这是正确的，因为灯笼的行为在苔藓块之间没有相互作用。 没有重叠，没有衰减，也没有条件逻辑。 每件作品都独立地对最终总数做出贡献。 

即使从字面上实现为循环中的重复加法，蛮力视图仍然是正确的。 操作总数正好是 N 次加法，对于 N 最多 1000 次来说这是微不足道的。 除了单次传递之外，无需进行优化。 

关键的观察是，所描述的过程不是状态转换的模拟问题，而是纯粹的聚合问题。 一旦我们认识到灯笼的状态只是一个运行总和，问题就简化为计算数组的总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(N) | O(1) | O(1) | 已接受 |
 | 直接求和 | O(N) | O(1) | O(1) | 已接受 |

 这两种方法实际上是相同的，但“直接求和”框架避免了任何不必要的解释开销。 

## 算法演练

 我们维护一个累加器，代表迄今为止累积的总燃烧时间。 我们只处理每个苔藓片一次，并将其值添加到该累加器中。 

### 步骤

 1. 读取整数 N，它表示存在多少块苔藓。 这决定了我们将处理多少个值。 
2. 将变量总计初始化为零。 该变量表示迄今为止处理的所有苔藓块的累积燃烧时间。 
3. 迭代表示燃烧时间的 N 个整数。 对于每个值 Hi，将其直接添加到总计中。 这反映了灯笼在移动到下一块之前完全消耗了那块苔藓。 
4. 处理完所有值后，输出总计作为最终答案。 

### 为什么它有效

在迭代中的每个点，总计等于迄今为止处理的所有苔藓块的总和。 由于每块苔藓都只被处理一次并贡献其全部价值，因此最终的总数是所有 Hi 的总和。 元素之间没有依赖性，因此重新排序或分组不会改变结果。 因此，累加器与灯笼总燃烧时间的精确定义相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input().strip())
    arr = list(map(int, input().split()))
    print(sum(arr))

if __name__ == "__main__":
    main()
```该实现直接依赖于 Python 的内置 sum，它对输入列表执行单次线性传递。 这与算法中描述的维护运行累加器完全一致。 读取输入使用快速 I/O 以避免不必要的开销，尽管对于 N 高达 1000 而言性能并不重要。 

其他语言中的一个常见错误是使用不能容纳最多 10^12 的值的整数类型。 在 Python 中，这是使用任意精度整数自动处理的，因此除了使用单个变量之外不需要特别注意。

 ## 边缘情况

 对于 N = 1，算法读取单个值并立即输出它。 例如，输入`1 10`将总计初始化为 0，添加 10，并打印 10，与灯笼燃烧时间的定义相匹配。 

对于最大值，例如`1000`的副本`10^9`，循环按顺序添加每个值。 Python 中累加器从 0 增长到 10^12，没有任何中间截断，从而产生正确的最终结果。 在具有固定宽度整数的语言中，这是通常会发生溢出的地方，但逻辑本身仍然正确。 

如果所有值都相同，则说`3 7 7 7`，该算法执行相同数字的重复加法。 循环的结构不假设唯一性，因此最终的总和自然变为 21，与预期的聚合行为相匹配。
