 ## 解决方案
 ## 问题理解

 网格代表一个值字段，其中每个单元格包含一个描述“气味强度”的非负数。 任务不是找到单个最佳矩形，而是检查网格的每个可能的子矩形并检查其总和是否等于给定的目标值 k。 

每当这样的矩形存在时，其中的所有单元格就变得“重要”。 在最终输出中，如果某个单元属于至少一个总和恰好为 k 的有效矩形，则该单元将被保留。 如果它从未出现在任何此类矩形中，则将其替换为零。 

关键的困难在于矩形重叠严重，因此单个单元格可以通过左上角和右下角的许多不同选择来验证。 

约束 n, m ≤ 100 足够小，每个维度的二次或三次方法都可能通过，但任何接近直接枚举所有矩形的方法都会变得太慢。 仅当每个操作都非常便宜且优化良好时，网格大小才允许总工作量约为 10^8 个单元，否则在 Python 中将会超时。 

一个天真的想法是使用前缀和来计算每个可能的矩形的总和，然后标记单元格，但这会导致 n 和 m 上的四个嵌套循环，产生大约 10^8 的矩形，并且对于每个矩形，我们仍然需要标记其面积，这使其远远超出了可行的限制。 

当 k 等于 0 时，就会出现第二个微妙的问题。 由于所有值都是非负的，因此在这种情况下有效矩形完全由零组成。 任何依赖于缩小或扩展窗口的解决方案都必须仔细处理长零段，否则可能会错过有效的子数组或对它们进行过度计数。 

## 方法

 暴力方法是枚举所有对的顶行和底行、所有对的左列和右列，使用预先计算的前缀和表计算矩形的总和，如果匹配 k，则标记该矩形中的所有单元格。 

即使前缀和允许 O(1) 矩形和查询，矩形的数量仍然是 O(n^2 m^2)。 当 n = m = 100 时，这是 10^8 个矩形。 由于在最坏的情况下，每个成功的矩形都需要对可能为 O(nm) 的单元进行额外的标记工作，因此总成本很快变得不可行。 

关键的观察是我们实际上不需要直接检查任意的二维矩形。 如果我们修复顶部和底部的行，问题就会分解为列上的一维问题。 对于每一列，我们累加这两行之间的总和，生成一个压缩数组。 这些行之间的每个有效矩形现在只是一个连续的子数组，其总和等于 k。 

因为网格中的所有数字都是非负的，所以可以使用两指针滑动窗口有效地解决这个一维子数组问题。 这避免了每对的散列或前缀和查找，并将每个行对计算减少到以 m 为单位的线性时间。 

一旦我们找到固定行对的所有有效子数组，我们仍然需要有效地标记整个矩形。 直接填充每个矩形的每个单元格将重新引入立方因子。 相反，我们将更新存储在 2D 差异数组中，因此每个矩形都在 O(1) 中做出贡献，并且最终的前缀和重建确定了哪些单元被覆盖。 

这将问题从显式枚举矩形转变为枚举行带并查找有效的列间隔。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有矩形进行暴力破解 | O(n^2 m^2 (n+m)) | O(n^2 m^2 (n+m)) | O(1) | O(1) | 太慢了 |
 | 修复行+前缀和| O(n^2 m^2) | O(n^2 m^2) | O(纳米) | 边界太慢 |
 | 修复行+滑动窗口+2D diff | O(n^2 m) | O(n^2 m) | O(纳米) | 已接受 |

 ## 算法演练

1.固定顶行索引并逐渐向下延伸底行索引。 对于每个扩展，维护两行之间的按列运行的值之和。 这会将 2D 网格压缩为 1D 数组，表示当前波段的垂直总和。 
2. 对于当前行带，使用滑动窗口搜索该一维数组中总和等于 k ​​的所有连续子数组。 由于所有值都是非负的，因此扩展右指针会增加总和，缩小左指针会减少总和，从而保证线性行为。 
3. 每次找到总和为 k 的子数组时，将其解释为从当前顶行到底行、从左列 l 到右列 r 的矩形。 
4. 不是直接标记该矩形中的每个单元格，而是应用 2D 差异更新，以便在恒定时间内记录矩形。 这确保了即使矩形很大，它的贡献仍然是 O(1)。 
5.处理完所有行对和所有有效列间隔后，将差值数组转换为前缀和网格。 最终网格中的每个单元格指示有多少个有效矩形包含它。 
6. 通过保留具有正覆盖范围的单元格的原始网格值并将其他值设置为零来产生最终答案。 

正确性取决于以下事实：每个矩形都是由压缩列表示中的一对行和一个有效子数组唯一确定的。 滑动窗口为每个行对精确地枚举所有此类子数组一次，并且差异数组保证每个矩形中的所有单元都被一致标记，而不会遗漏或重复影响正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    diff = [[0] * (m + 1) for _ in range(n + 1)]

    for top in range(n):
        col_sum = [0] * m

        for bot in range(top, n):
            for j in range(m):
                col_sum[j] += a[bot][j]

            l = 0
            cur = 0

            for r in range(m):
                cur += col_sum[r]

                while l <= r and cur > k:
                    cur -= col_sum[l]
                    l += 1

                if cur == k:
                    diff[top][l] += 1
                    diff[top][r + 1] -= 1
                    diff[bot + 1][l] -= 1
                    diff[bot + 1][r + 1] += 1

    for i in range(n):
        for j in range(m):
            diff[i][j] += diff[i - 1][j] if i > 0 else 0
    for i in range(n):
        for j in range(m):
            diff[i][j] += diff[i][j - 1] if j > 0 else 0

    out = []
    for i in range(n):
        row = []
        for j in range(m):
            if diff[i][j] > 0:
                row.append(str(a[i][j]))
            else:
                row.append("0")
        out.append(" ".join(row))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案为每对行维护一个动态列和数组，然后使用滑动窗口枚举所有有效的列间隔。 使用 2D 差分结构将每个间隔转换为矩形更新。 最终的双前缀和重建覆盖计数，输出步骤只是根据单元格是否包含在任何有效矩形中来过滤原始网格。 

一个微妙的点是，滑动窗口仅在所有网格值都是非负的情况下才起作用。 如果允许负值，则缩小和扩展窗口所需的单调性将被破坏，并且需要基于散列的前缀和方法。 

差异数组还避免了尝试直接绘制矩形的常见错误。 如果没有它，解决方案将退化为每个矩形更新 O(nm) 个单元，这太慢了。 

## 工作示例

 考虑一个小网格，其中有效矩形仅存在于少数区域。 我们跟踪单个行带和由此产生的列压缩。

我们跟踪滑动窗口：

 ## 边缘情况

 当 k 等于 0 时，每个有效矩形必须完全由零组成。 滑动窗口仍然可以正确运行，因为总和从零开始，并且仅在遇到正值时才扩展。 对于像一行零这样的输入，每个子数组都是有效的，并且差异数组标记完整的网格，这是正确的，因为每个单元格都位于某个零和矩形中。 

对于具有孤立的非零尖峰的网格，只会检测到与 k 完美平衡的矩形。 由于每当总和超过 k 时滑动窗口就会缩小，因此它可以避免错误地将矩形延伸到有效边界之外，即使当行带中间出现大值时也是如此。 

像 1x1 这样的小网格很自然地得到处理，因为行对循环退化为单次迭代，并且滑动窗口直接评估唯一可能的子数组。
