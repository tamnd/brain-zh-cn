 ## 解决方案
 ## 问题理解

 我们得到一个代表图片的字符网格，其中每个单元格要么是空的，要么是已填充的。 任务是判断填充的单元格是否正好形成一个加号形状。 

有效的加号形状具有单个中心填充单元。 从该中心开始，必须至少有一个填充单元沿上、下、左、右四个方向连续延伸。 这些延伸部分必须是没有间隙的直线段。 网格中的每个填充单元都必须属于这个单一结构，这意味着没有额外的组件，没有孤立的单元，也没有二级分支。 

因此，我们正在验证的结构不仅仅是“看起来像一个加号”，而是一个非常严格的连接模式：一个中心，四个直臂，网格中没有其他任何地方。 

网格大小可以大到 500 x 500，这意味着最多 250,000 个单元格。 任何试图以二次或更糟糕的方式重复扫描或扩展许多候选者的解决方案都会带来不必要的开销。 然而，即使对所有单元进行完整的线性扫描也是完全可以接受的，因为 250,000 次操作是微不足道的。 

一些边缘情况很快就会打破天真的推理。 

第一个陷阱是多个候选中心。 例如，如果有两条独立的垂直星线：```
.*....
.*....
.*....
..*...
..*...
..*...
```即使每一列单独地类似于一条手臂，这也不是一个单一的优点。 正确答案是否定的，因为有不止一个连接结构。 

第二个陷阱是手臂骨折。 如果中心存在但一个方向有间隙：```
..*..
..*..
.*.*.
..*..
.....
```这是无效的，因为臂不连续。 

第三个陷阱是加号之外的杂散细胞：```
..*..
.***.
..*..
..*..
*....
```即使存在加号，左下角的额外星号也会使配置无效。 

关键的挑战不是发现优势，而是同时加强全球独家性和连续性。 

## 方法

 一种蛮力方法是尝试将每个星细胞作为潜在的中心。 对于每个候选者，我们将在四个方向上扩展，标记访问过的单元格，并验证所有星星是否都被恰好覆盖一次。 

这在概念上是有效的，因为加号是由独特的中心和确定性臂定义的。 然而，在密集网格中，成本会成为问题。 在最坏的情况下，大多数细胞都是星形，我们可能会尝试 O(h·w) 中心，并且每次扩展扫描最多 O(h + w)，导致 O(h·w·(h + w)) 复杂度。 500×500，这已经远远超出了极限。 

关键的观察结果是，有效的 plus 具有非常严格的结构。 恰好有一个单元格的四个方向都可以连续延伸。 该细胞必须在所有四个方向上至少有一个邻居，并且所有其他恒星必须正好位于穿过该细胞的四条直线中的一条上。 这意味着我们不需要测试每个细胞，我们只需要识别唯一的中心并验证手臂一次。 

我们可以通过扫描一颗上、下、左、右至少有一颗恒星的恒星来找到中心。 一旦我们找到这样的候选者，我们就会通过扩展它来完全验证结构并确保覆盖范围与网格中的所有星星完全匹配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(h·w·(h+w)) | O(h·w·(h+w)) | O(1) | O(1) | 太慢了 |
 | 中心检测+验证| O(h·w) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 扫描网格并收集所有星星位置，同时检查候选中心。 

如果一个单元格在所有四个方向上至少有一颗星星，则该单元格是候选中心。 这个条件确保它可能是加号的交集。 
2. 如果不存在候选中心，则立即返回NO。 

有效的加号必须恰好有一个交点。 
3. 对于每个候选中心，尝试验证。 

我们选择一个并假设它是中心。 
4. 从中心开始，向上扩展，直到找到非星体，记录所有访问过的星体细胞。 

这定义了垂直臂。 
5. 重复同样的向下、向左、向右扩展。 

这四次遍历收集了应该属于该结构的所有单元格。 
6. 收集所有可到达的臂单元后，验证两个条件：

 首先，每个收集到的单元格必须是网格中的一颗星星。 

其次，收集的单元格总数必须等于网格中星星的总数。 
7. 如果任何候选中心都满足这两个条件，则返回 YES。 否则，返回NO。 

### 为什么它有效

 有效的加号完全由单个交点和从该交点延伸的四个最大直线段来表征。 任何偏差，无论是额外的星星还是缺少连续性，都会改变距中心的可达性或星星的总数。 通过从中心重建形状并将其与整组恒星进行比较，我们同时增强了连通性和排他性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    h, w = map(int, input().split())
    g = [list(input().strip()) for _ in range(h)]

    stars = 0
    for i in range(h):
        for j in range(w):
            if g[i][j] == '*':
                stars += 1

    def valid(i, j):
        if g[i][j] != '*':
            return False

        visited = set()

        # up
        x = i
        while x >= 0 and g[x][j] == '*':
            visited.add((x, j))
            x -= 1

        # down
        x = i + 1
        while x < h and g[x][j] == '*':
            visited.add((x, j))
            x += 1

        # left
        y = j - 1
        while y >= 0 and g[i][y] == '*':
            visited.add((i, y))
            y -= 1

        # right
        y = j + 1
        while y < w and g[i][y] == '*':
            visited.add((i, y))
            y += 1

        # include center
        visited.add((i, j))

        return len(visited) == stars

    for i in range(h):
        for j in range(w):
            if g[i][j] == '*':
                if valid(i, j):
                    print("YES")
                    return

    print("NO")

if __name__ == "__main__":
    solve()
```网格被直接读入内存，我们首先计算所有星星。 这为我们提供了稍后使用的全局不变量：任何有效的重建都必须与该总数完全匹配。 

这`valid`函数假设给定的单元格为中心，并向所有四个方向扩展，直到形状破裂。 每一颗访问过的恒星都会被记录下来。 关键的想法是，一个正确的中心将能够准确地到达每颗恒星一次，因为该结构是一个单一的加号，没有分支。 

最后，我们测试每个星细胞作为可能的中心。 第一个成功的匹配将终止程序。

 ## 边缘情况

 极端情况是最小的有效加值，其中中心是唯一的单元格。 在这种情况下，算法将单个星星视为有效中心，但方向扩展立即停止，并且访问计数与一颗星星完全匹配。 

另一种情况是在一个粗交叉中存在多个潜在中心。 只有其中一个能够正确覆盖整组恒星。 任何其他候选者都会错过外臂或包含不正确的重叠，从而导致访问计数不匹配。 

最后的边缘情况是一个接近正值的形状，缺少一个臂段。 从中心开始的扩张将提前停止在该方向上，从而将访问的覆盖范围减少到低于总恒星数，从而迫使拒绝。
