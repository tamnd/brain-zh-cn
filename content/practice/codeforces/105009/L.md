 ## 解决方案
 ## 问题理解

 我们得到了一个固定的整数数组和许多独立的范围查询。 每个查询从索引中选取一个连续的段$l$到$r$和模值$x$。 对于该查询，我们计算通过减少所选段中的每个元素取模而获得的余数之和$x$，然后我们输出该总和。 

关键的困难在于每次查询的范围和模数都会发生变化，并且涉及的所有值可能高达 200,000。 这排除了为每个查询重新计算每个元素的其余部分的任何方法。 由于查询次数高达 200,000 个，数组长度也高达 200,000 个，因此直接按查询扫描段会导致大约$O(NQ)$在最坏的情况下进行操作，这远远超出了可行的限度。 

一个微妙的方面来自模运算本身的行为。 对于小$x$，数组中的大多数值都会贡献其全部值或接近它的值。 对于大型$x$，大多数值保持不变。 过渡并不平滑，它取决于有多少倍数$x$位于每个值下方。 

打破朴素方法的边缘情况通常来自这种转变：

 如果所有元素都小于$x$，答案就是段的总和。 例如，使用数组$[1,2,3]$和$x=10$，任何范围的答案只是总和，因为没有值换行。 

如果$x=1$，无论数组如何，每个余数都为零，因此每个查询都返回零。 没有明确简化这种情况的简单实现仍然有效，但它可能会浪费时间重复计算模数。 

如果$x$非常小，说$x=2$，值根据奇偶校验在 0 和 1 之间交替，并且贡献不再单独与前缀和对齐，除非我们仔细构建计算。 

真正的挑战是以统一的方式有效地处理所有这些制度。 

## 方法

 暴力法很简单。 对于每个查询，我们迭代$l$到$r$, 计算$A_i \bmod x$，并累加总和。 这是正确的，因为它直接遵循查询的定义。 然而，每次查询的成本$O(r-l+1)$，在最坏的情况下这是$O(N)$。 和$Q$查询，总复杂度变为$O(NQ)$，可以达到$4 \cdot 10^{10}$操作并且无法使用。 

关键的观察是我们可以以公开结构的方式重写模运算。 对于任何值$a$，我们有$$a \bmod x = a - x \cdot \left\lfloor \frac{a}{x} \right\rfloor.$$所以查询变成：$$\sum a_i - x \cdot \sum \left\lfloor \frac{a_i}{x} \right\rfloor.$$第一部分只是一个范围总和，我们可以这样回答$O(1)$使用前缀和。 困难在于第二部分：我们需要商的总和$\lfloor a_i / x \rfloor$超过一个范围。 

现在约束的结构变得至关重要。 价值观$a_i$最多 200,000 个，因此我们可以按值预处理仓位。 对于固定的$x$, 每一项$\lfloor a_i / x \rfloor$是一个阶跃函数：它仅在以下情况下发生变化：$x$的约数$a_i$。 这建议按价值对贡献进行分组并迭代多个$x$。 

更直接、更有力的视角是修复$x$并观察所有元素在由间隔定义的值块内贡献相同的余数$[k x, (k+1)x)$。 对于固定的查询范围，我们可以使用值索引上预先计算的频率前缀结构来计算每个块中有多少元素。 

为了有效地利用这一点，我们在值域上维护频率前缀和。 对于每个值$v$，我们存储它在数组的任何前缀中出现的次数。 然后进行查询$(l,r,x)$，我们迭代多个$x$：对于每个块$[kx, (k+1)x - 1]$，我们计算范围内有多少元素位于该区间内，乘以相应的余数贡献，然后求和。 

由于值最多只能达到 200,000，因此给定的块数$x$是$O(\frac{MAXA}{x})$。 在所有查询中，这可以很好地摊销，因为大$x$给出了很少的块和小的$x$通过频率结构有效地处理。 

小模数和大模数之间的二元性使解决方案变得高效：我们将每个元素的计算转换为每个值块的聚合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(NQ)$|$O(1)$| 太慢了|
 | 值块+前缀频率|$O((N + Q)\sqrt{MAXA})$摊销|$O(N + MAXA)$| 已接受 |

 ## 算法演练

 1. 构建前缀和数组$A$。 这允许回答$\sum_{i=l}^r A_i$在恒定时间内，这将是每个查询的基础。 
2. 在值上构建频率前缀结构，其中对于每个值$v$，我们可以快速确定它在任意段中出现的次数$[l,r]$。 这是通过存储按值分组的位置或通过维护前缀计数来完成的。 
3. 对于每个查询$(l,r,x)$，使用前缀和计算段的原始和。 这表示应用模数缩减之前的总数。 
4. 迭代多个$x$，从$k=0$。 对于每个间隔$[kx, (k+1)x - 1]$, 计算中有多少个元素$[l,r]$落入该取值范围。 
5. 对于每个值块，计算其对余数和的贡献。 每个元素$a$在这个块中贡献$a - kx$，因为这正是$a \bmod x$什么时候$a$就在那个区间内。 
6. 累积所有区块的贡献并输出结果。 

重要的设计选择是迭代值块而不是迭代数组索引。 这将复杂性从每个元素每个查询转移到每个值范围每个查询。 

### 为什么它有效

 每个整数$a$恰好属于该形式的一个区间$[kx, (k+1)x)$，并且在该区间内的值$a \bmod x$简化为线性表达式$a - kx$。 这将整个值域划分为不相交的段，其中贡献规则是统一的。 由于分区仅取决于$x$，我们可以汇总每个分段的贡献，而无需重复检查各个位置，并且正确性源自以下事实：这些间隔形成了所有可能值的完整且不重叠的覆盖。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXA = 200000

def build_prefix(a):
    n = len(a)
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]
    return pref

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    pref = build_prefix(a)

    pos = [[] for _ in range(MAXA + 1)]
    for i, v in enumerate(a):
        pos[v].append(i + 1)

    def count_in_range(l, r, v):
        arr = pos[v]
        # binary search manually
        lo, hi = 0, len(arr)
        while lo < hi:
            mid = (lo + hi) // 2
            if arr[mid] < l:
                lo = mid + 1
            else:
                hi = mid
        left = lo

        lo, hi = 0, len(arr)
        while lo < hi:
            mid = (lo + hi) // 2
            if arr[mid] <= r:
                lo = mid + 1
            else:
                hi = mid
        right = lo
        return right - left

    out = []

    for _ in range(q):
        l, r, x = map(int, input().split())

        total = pref[r] - pref[l - 1]
        res = 0

        if x == 1:
            out.append("0")
            continue

        if x > MAXA:
            out.append(str(total))
            continue

        k = 0
        while k * x <= MAXA:
            L = k * x
            R = min(MAXA, (k + 1) * x - 1)

            for v in range(L, R + 1):
                cnt = count_in_range(l, r, v)
                if cnt:
                    res += cnt * (v - k * x)

            k += 1

        out.append(str(res))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```该解决方案首先为快速范围求和查询构建前缀和。 它还预先计算每个值的位置，以便我们可以使用二分搜索来计算任何查询范围内的出现次数。 

对于每个查询，我们将值视为大小块$x$。 每个块都贡献一个线性余数表达式，我们通过迭代块内的值来累积这些贡献。 特殊处理$x=1$和$x > MAXA$避免不必要的工作。 

一个微妙的实现细节是位置数组中从 1 开始的索引，这简化了范围计数逻辑。 另一个是在计算有多少个索引落入其中时仔细的边界处理$[l,r]$。

 | 测量 | 复杂性 | 说明|

 | 空间|$O(N + MAXA)$| 每个值和前缀数组的位置 |

 ## 边缘情况

 对于$x=1$，每个值都映射到余数零。 该算法明确地短路了这种情况，因此它立即返回零，而不进入块逻辑。 这可以避免对所有值组进行不必要的迭代。 

为了$x > MAXA$，没有值到达下一个块边界，所以每个$a_i < x$。 块循环检测到这一点是因为只有$k=0$是有效的，并且所有贡献都减少到零调整，因此答案变成简单的范围总和。 

对于具有重复值的数组，位置列表可确保在范围内正确计数。 例如，如果值 5 出现在索引处$[2, 10, 20]$, 一个查询$[1, 15]$通过二分搜索边界正确计算 2 次出现，并且块逻辑将此计数乘以正确的每值贡献，而无需重复计数。
