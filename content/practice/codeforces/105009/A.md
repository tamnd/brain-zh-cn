 ## 解决方案
 ## 问题理解

 我们得到一个排列在单行中的整数序列，并要求我们找到该序列的一个连续段，该段最多使用三个不同的值，同时尽可能长。 

将数组视为 Numerica 中的交易时间线。 每个数字都是当时正在交易的一种商品。 我们希望选择一段连续的时间，其中市场最多只处理三种商品。 在所有这些有效的延伸中，我们想要长度最大的一个。 

输出只是一个数字，即最佳可能拉伸的长度。 

数组大小最大可达 100000，这会立即排除任何尝试显式检查每个子数组的解决方案。 在最坏的情况下，二次或三次方法需要大约 10^10 次运算，这远远超出了一秒的运行时间。 这推动我们采用线性或近线性技术，通常涉及滑动窗口或两个指针。 

当考虑贪婪扩张时，会出现一个微妙的问题。 如果我们扩展一个段直到它违反约束，我们必须小心如何收缩它。 每次违规后从头开始的幼稚方法可能会错过最佳窗口或变得太慢。 

例如，考虑一个像这样的数组`[1, 2, 3, 4, 1, 2, 3]`。 最佳分段是仅包含三个不同值的任何窗口，例如`[1, 2, 3, 4]`是无效的，但是`[2, 3, 4, 1]`由于有四个不同的值，它也是无效的。 正确答案是 3，来自以下部分：`[1, 2, 3]`。 如果我们在看到第四个不同值时错误地重新启动，我们可能会重复丢弃有用的重叠并进行不必要的重新计算。 

## 方法

 暴力法很简单。 我们考虑每个起始索引，并将子数组向右扩展，同时跟踪出现了多少个不同的数字。 对于每次开始，我们都会扩展，直到达到四个不同的值，并记录该点之前看到的最佳有效长度。 

这是有效的，因为它显式地检查每个候选片段。 问题在于它的成本。 对于 N 个起始位置中的每一个，我们可能会扫描最多 N 个元素，并且以简单的方式维护不同的计数会增加开销。 即使使用散列，最坏情况的复杂度也是 O(N²)，当 N = 10⁵ 时，这会导致大约 101⁰ 次操作，显然太慢了。 

关键的观察是我们实际上不需要从每个索引重新启动扫描。 当我们向前移动右指针时，左指针只需要向前移动即可恢复最多三个不同值的约束。 一旦一个值完全离开窗口，它就会从我们的频率结构中删除。 两个指针的这种单调移动保证了每个元素最多进入和离开窗口一次。 

这正是滑动窗口技术：我们维护一个始终有效的窗口（最多三个不同的值），然后贪婪地扩展它，同时通过从左侧收缩来修复违规问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N²) | O(1) 到 O(N) | 太慢了 |
 | 最优滑动窗口| O(N) | O(1) 到 O(N) | 已接受 |

 ## 算法演练

 我们维护一个窗口`[l, r]`以及其中值的频率图。 

1. 初始化`l = 0`,`best = 0`，和一个空的频率图。 

这将设置一个空的滑动窗口。 
2. 向右移动指针`r`从左到右穿过阵列。 

每一步都会向当前窗口添加一个新元素，逐渐探索以`r`。 
3、添加时`A[r]`，增加其在地图中的出现频率。 

这可以精确计算每个值在当前窗口内出现的次数。 
4. 如果映射中不同键的数量大于 3，则从左侧缩小窗口。 

我们反复减少频率`A[l]`并移动`l`向前直到窗口再次包含最多三个不同的值。 这是必要的，因为任何无效窗口都无法得出答案。 
5. 恢复有效性后，将答案更新为`best = max(best, r - l + 1)`。 

在此刻，`[l, r]`是结束于的最长有效子数组`r`，因此可以安全地将其视为全局最大值。 
6. 继续直到`r`到达数组末尾。 

### 为什么它有效

 该算法依赖于一个关键的不变量：在`r`, 窗户`[l, r]`最多包含三个不同的值，并且`l`是当前保持该属性的最小索引`r`。 因为我们只会移动`l`必要时前进，我们永远不会丢弃结束于的可能更好的窗口`r`。 每个有效的子数组在某个点都被表示为窗口端点，并且这些端点上的最大值就是全局答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    freq = {}
    l = 0
    best = 0
    
    for r in range(n):
        freq[a[r]] = freq.get(a[r], 0) + 1
        
        while len(freq) > 3:
            freq[a[l]] -= 1
            if freq[a[l]] == 0:
                del freq[a[l]]
            l += 1
        
        best = max(best, r - l + 1)
    
    print(best)

if __name__ == "__main__":
    solve()
```该解决方案直接围绕滑动窗口不变量构建。 字典`freq`跟踪多重性和条件`len(freq) > 3`检测窗口何时违反约束。 

内部 while 循环至关重要：它确保窗口始终在违规后立即修复。 当密钥的频率降至零时，无需删除密钥，`len(freq)`将是不正确的，这是错误的常见来源。 

表达式`r - l + 1`计算当前窗口大小并表示结束于的最佳有效子数组`r`。

 ## 边缘情况

 最小输入，例如`1`测试算法是否在不进入循环的情况下正确初始化答案。 窗口以单个元素开始和结束，并且频率图包含一个键，立即产生输出 1。 

完全均匀的数组，例如`5 5 5 5 5`永远不会触发收缩条件。 频率图的大小始终为 1，因此窗口单调增长到全长。 这证实了该算法没有人为地缩小有效窗口。 

严格交替的模式，例如`1 2 3 4 5 6`力量反复收缩。 当出现第四个不同值时，左指针前进，直到只剩下三个。 当频率降至零时，这会测试删除逻辑的正确性，并确保重复计数检查在整个执行过程中保持准确。
