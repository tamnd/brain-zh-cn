 ## 解决方案
 ## 问题理解

 学生很多，但只有相对少数的人有明确的“必须在一起”的关系。 这些关系形成了学生的无向图。 每个学生都从一张编号的卡片开始，并且只能沿着最终图表中存在的友谊链接交换卡片。 您可以在任何事情开始之前添加额外的友谊边缘，目标是尽量减少添加的此类额外边缘的数量。 

关键要求不是关于单一的最终安排，而是关于稳健性：无论初始卡牌如何分配，都必须始终能够使用沿着友谊边缘的交换来达到每对最好的朋友最终持有相同卡牌值的状态。 

重要的结构是交换仅限于友谊图的连接组件。 在连接的组件内部，卡可以任意排列，但在组件之间，它们永远是隔离的。 因此，整个问题是关于最终连接的组件如何与最好的朋友边缘施加的“必须相等”约束相互作用。 

这些约束多达二十万个最好的朋友关系，因此任何解决方案都必须本质上将图简化为线性或近线性过程，例如联合查找或基于 DFS 的组件分析。 边或节点中的任何二次方都是不可能的。 

当最好的边缘形成链或循环时，会出现微妙的边缘情况。 例如，如果最好的朋友关系是 1-2、2-3、3-4，那么即使每个边仅谈论相邻对，传递要求也会强制所有四个节点表现为单个同步单元。 仅单独检查边缘的简单方法在这里失败了，因为它忽略了通过连接的传播。 

## 方法

 蛮力的想法是模拟系统：尝试添加友谊边集，然后对于每个可能的初始分配，尝试验证是否始终可以安排交换以使每个最好的朋友对最终都相等。 这很快就变得不可行，因为可能的初始卡分配数量是天文数字，甚至检查单个配置也需要推理组件内部的可达性和排列。 

结构的简化来自于分离两层。 一层是友谊图，它决定了哪里可以进行交换。 另一层是施加等式约束的最好的朋友图。 在友谊图的任何连接组件内，交换允许我们自由地排列值，因此唯一重要的是哪些节点最终位于同一组件中。 

关键的观察结果是，等式约束沿着最好的朋友图中的连通性传播。 如果节点 A 必须等于节点 B，并且 B 必须等于 C，那么 A、B 和 C 都必须被迫进入这样一种情况：无论初始分布如何，系统始终可以协调它们的值。 只有当友谊结构足够强大以允许这些受约束的节点充当单个灵活单元时，这才成为可能。 

添加边的最小数量正是确保最好的朋友图的每个连接组件完全受到友谊结构“支持”所需的数量，这意味着受约束的节点永远不会被分割成独立的交换区域。 这减少了将每个最好的朋友组件连接到一个统一的友谊组件中，这需要使每个这样的组件在内部连接（如果尚未连接）。 

实际上，这意味着大小为 k 的最好朋友图的每个连接组件需要 k 减去一条边才能在友谊系统下完全内部连接。

 ## 算法演练

 我们继续将最好的朋友图压缩为连接的组件，因为约束仅通过连接传播。 

### 1. 构建最好朋友图的连接组件

 我们将每个学生视为一个节点，将每个最好的朋友关系视为一条边。 使用 DFS 或 DSU，我们可以识别所有连接的组件。 此步骤捕获传递相等压力：同一组件中的任何两个节点在任何有效的最终分配下都必须表现一致。 

### 2.测量每个组件的尺寸

 对于每个连接的组件，我们计算它包含的节点数量。 这个大小决定了它内部存在多少个独立的同步点。 

### 3. 计算所需的内部连接

 仅当友谊系统允许其节点之间完全内部混合时，大小为 k 的组件才是“安全的”。 这需要至少 k 减去一条边，以确保组件可以表现得像一个灵活的单元，而不是零散的部件。 

如果一个组件已经跨越多个友谊连接区域，我们必须在概念上将它们“缝合”在一起。 每一个缺失的联系都对应着一段新的友谊。 

### 4. 对所有分量求和

 我们对所有连接的组件求和（大小减一）。 这给出了确保每个最好的朋友约束总是能够得到满足而不管初始卡分发如何所需的最小数量的额外友谊。 

### 为什么它有效

 在最好的朋友图的每个连接组件中，所有节点都通过平等要求链相互约束。 如果友谊结构没有完全连接它们，一些节点将被困在单独的交换区域中，从而无法保证在任意初始分配下具有相同的值。 通过强制每个这样的组件在内部完全连接，我们确保任何分配都可以足够自由地重新排列，以始终满足每个最好朋友边上的相等约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    
    adj = {}
    
    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        if a not in adj:
            adj[a] = []
        if b not in adj:
            adj[b] = []
        adj[a].append(b)
        adj[b].append(a)

    visited = set()

    def dfs(start):
        stack = [start]
        visited.add(start)
        cnt = 0
        while stack:
            u = stack.pop()
            cnt += 1
            for v in adj.get(u, []):
                if v not in visited:
                    visited.add(v)
                    stack.append(v)
        return cnt

    answer = 0

    for node in adj:
        if node not in visited:
            size = dfs(node)
            answer += max(0, size - 1)

    print(answer)

if __name__ == "__main__":
    solve()
```该实现为最好的朋友图构建邻接列表并运行迭代 DFS 来计算组件大小。 每次发现新的未访问节点时，我们都会探索其完整连接的组件并计算其大小。 该组件的贡献以大小减一的形式添加。 

一个微妙的实现细节是使用迭代 DFS 而不是大量递归遍历，这避免了长友谊链上的堆栈溢出。 另一个重要的点是迭代邻接字典，而不是假设节点从 1 到 n 是密集的，因为只有最好的朋友边的端点是相关的。 

## 工作示例

 ### 示例 1

 输入：```
5 3
1 2
2 3
4 5
```我们构建组件如下：

 | 步骤| 节点| 访问过的组件 | 元件尺寸|
 | ---| ---| ---| ---|
 | 1 | 1 | {1,2,3} | 3 |
 | 2 | 4 | {4,5} | 2 |

 总答案变为 (3−1) + (2−1) = 3。 

这演示了单独的最好的朋友集群如何独立地影响最终成本，因为每个集群必须在内部稳定。

 ## 边缘情况

 退化的情况是根本没有最好的朋友边缘。 该图没有约束，因此不需要额外的友谊。 该算法自然会返回零，因为没有要处理的组件。 

另一个例子是一长串最好的朋友关系。 尽管每个节点的度数最多为 2，但它们形成单个连接组件，并且该算法正确地将整个链视为大小为 k 的一个单元，贡献 k 减一。 

像星形这样的高度倾斜的图表也能正常运行。 中心将所有节点连接成一个组件，贡献变成叶子的数量，这与确保任意初始分布下的完全同步性所需的内部连接数量相匹配。
