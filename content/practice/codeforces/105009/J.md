 ## 解决方案
 ## 问题理解

 我们给定一个长度序列$N$仅包含值$0,1,2,3$。 所有元素都从船上开始$A$，我们必须让他们登机$B$通过反复采取前面$A$并将其附加到$B$。 这样做时，我们可以进行两个额外的转换：我们可以翻转中的所有值$A$通过映射$x \to 3-x$，我们可以反转当前的内容$B$。 

这个过程不仅仅是移动元素。 最终的安排是$B$必须满足结构约束：出现的每个不同值必须恰好形成一个连续的块。 换句话说，如果一个值多次出现$B$，它的所有出现都必须位于一个不间断的段中，没有其他值的交错。 

每个测试用例都要求使用字母的尽可能短的操作序列$c$（补充），$r$（撤销$B$）， 和$p$（推自$A$到$B$），实现有效的最终配置。 在所有具有最小长度的序列中，我们必须输出字典顺序最小的序列。 

约束条件足够严格$N$上升到$10^5$测试用例的总和也是$10^5$。 这立即排除了任何试图通过回溯或状态搜索来模拟任意操作交错的方法。 任何按操作分支或维护多个候选状态的解决方案都会退化为指数或至少二次行为。 

当假设分组纯粹与排序有关时，就会出现天真的推理的微妙失败案例。 例如，序列$0,1,0,1$不能仅通过任何推送的重新安排来修复； 人们可能认为反转或补充会有所帮助，但由于只存在全局变换，真正的限制是序列是否可以在最多几次全局翻转下变成“每个值单次运行”。 仅计算频率或假设排序总是可能的粗心方法将错误地接受此类情况。 

另一个常见的陷阱是以贪婪的方式将操作视为可自由交错，而实际上在流程中应用它们并不会改变正在构建的基本结构：每个元素仍然以原始顺序或完全相反的顺序使用，并且补码仅在全局范围内重命名值。 

## 方法

 蛮力观点是将其视为由以下定义的状态上的最短路径问题$(A, B)$加上我们是否应用了补集以及我们是否反转了。 每个步骤可以应用三个操作之一，我们搜索最短的有效序列。 这很快就变得不可行，因为$A$和$B$演变过来$N$操作，因此状态空间随着推送次数呈指数增长，甚至表示所有可达配置已经$O(4^N)$- 结构上类似。 

关键的观察结果是，两者都不是$c$也不$r$在序列内创建新的排序自由度。 补码仅一致地重命名值，而反转仅翻转我们读取最终序列的方向。 唯一真正的组合结构是元素被推送的顺序，除非我们决定反转整个流程，否则该顺序是固定的。 

这将问题分解为检查输入序列的恒定数量的全局变换。 我们只需要考虑是否应用补码和/或反转，然后验证结果序列是否已经满足“每个值单个连续块”条件。 由于只有四种可能性，因此问题从指数状态探索减少到每个测试用例四次线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力状态搜索 | 指数| 指数| 太慢了|
 | 尝试 4 种全局变换 |$O(N)$每次测试|$O(1)$| 已接受 |

 ## 算法演练

 1. 将原始序列视为碱基构型，以及其互补序列、反向序列和反向互补序列。 这四种情况代表了允许的全局操作的所有有意义的影响，因为补码和逆都是对合。 
2. 对于四个候选序列中的每一个，检查每个值是否$\{0,1,2,3\}$最多出现在一个连续的段中。 这相当于扫描序列并确保一旦我们留下一个值，以后就不会再遇到它。 
3. 对于每个有效候选者，计算运营成本。 碱基序列的成本为 0，应用补码加 1 运算，应用反向加 1 运算，应用两者加 2 运算。 
4. 选择操作次数最少的候选者。 如果多个候选者共享相同的成本，则选择字典顺序最小的操作字符串，我们在其中比较字符串$\{c,r,p\}$按字典顺序。 
5. 构建最终的操作序列，首先按字典顺序发出所选的全局操作，然后附加$N$推动$p$，因为每个元素必须恰好传输一次。 

这种结构有效的原因是补码和逆序不依赖于推动元素的进度。 稍后或较早应用它们不会改变最终的多重集结构$B$，仅对值和顺序进行解释。 因此，任何最佳解决方案都可以重新排列，以便所有全局转换在所有推送之前发生，而不会增加成本或破坏有效性。 

### 为什么它有效

 关键的不变量是影响可行性的唯一自由度是元素消耗的线性顺序$A$, possibly reversed once globally. 补集不会影响邻接结构，它只会重命名标签。 因此，可行性条件仅取决于固定排列（原始排列或反转排列）是否已经具有每个标签形成单个区间的属性。 由于此属性在重新标记时保留，因此检查四个全局转换会耗尽所有可能性。 

任何在流程中应用操作的交错策略都可以转换为等效策略，其中所有$c$和$r$首先应用操作，然后是所有操作$p$操作，而不改变最终顺序或增加操作数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ok(arr):
    seen = [False] * 4
    active = [False] * 4
    for x in arr:
        if not active[x]:
            if seen[x]:
                return False
            active[x] = True
            seen[x] = True
        for v in range(4):
            if v != x:
                active[v] = False
    return True

def build_ops(use_c, use_r):
    ops = []
    if use_c:
        ops.append('c')
    if use_r:
        ops.append('r')
    ops.append('p')
    return ''.join(ops)

def solve():
    t, n = map(int, input().split())
    comp = [3, 2, 1, 0]
    
    for _ in range(t):
        a = list(map(int, input().split()))
        
        cand = []
        
        # identity
        if ok(a):
            cand.append((0, build_ops(False, False)))
        
        # complement
        a2 = [comp[x] for x in a]
        if ok(a2):
            cand.append((1, build_ops(True, False)))
        
        # reverse
        a3 = a[::-1]
        if ok(a3):
            cand.append((1, build_ops(False, True)))
        
        # reverse + complement
        a4 = [comp[x] for x in a3]
        if ok(a4):
            cand.append((2, build_ops(True, True)))
        
        cand.sort()
        cost, base = cand[0]
        
        # append p's
        print(base[:-1] + 'p' * n)

if __name__ == "__main__":
    solve()
```该解决方案将问题分为结构验证和操作重构。 这`ok`函数通过跟踪是否已看到某个值以及其当前段是否仍处于活动状态来检查单块条件。 转换情况与在任何推送之前应用补充和/或反转完全对应。 

输出构造利用了所有推送操作实际上都是相同的事实，因此它们可以表示为重复的后缀`p`。 这避免了明确地模拟不断发展的电路板。 

## 工作示例

 考虑一个序列，其中值已经出现在干净的块中，例如$1,1,0,0,3,3$。 恒等变换已经满足条件，因此算法选择零全局操作并且仅输出推送。 扫描在其段关闭后再也不会看到值重新出现，从而确认了有效性。 

现在考虑一个序列$0,1,0,1$。 身份检查失败，因为值 0 在离开其段后再次出现。 还检查补码和反向情况，但没有一个为每个值生成单区间结构。 这说明了为什么该问题保证存在：在有效输入中，四种转换中至少一种会产生干净的分割。 

| 转型| 序列 | 有效的？ |
 | ---| ---| ---|
 | 身份| 0 1 0 1 | 0 1 0 1 没有 |
 | 补充 | 3 2 3 2 | 3 2 3 2 没有 |
 | 反向| 1 0 1 0 | 1 0 1 0 没有 |
 | 反向+补偿| 2 3 2 3 | 2 3 2 3 没有 |

 该轨迹显示了算法如何系统地排除无效的结构方向。

 ## 边缘情况

 一个关键的边缘情况是序列仅在反转后才有效。 例如，像这样的序列$0,0,1,1,2,2$已经有效，但是$2,2,1,1,0,0$需要反转以匹配相同的结构。 该算法通过显式测试反向配置并确认每个值出现在单个连续间隔中来处理此问题。 

另一种边缘情况是需要补充时。 由于值是对称的$x \to 3-x$，原始形式失败的序列在重命名后可能会变得有效。 该检查通过独立评估两个标签空间而不是假设数字的固定含义来确保正确性。
