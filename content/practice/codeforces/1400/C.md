 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串$s$和一个距离参数$x$。 存在未知的原始二进制字符串$w$相同长度的。 从$w$, 字符串$s$是使用确定性规则生成的：中的每个位置$s$最多查看两个位置$w$， 一$x$向左走一步$x$向右迈出一步。 如果其中任何一个参考位置$w$包含1，则对应位置$s$变为1。否则变为0。 

任务是重建任何有效的$w$可能会产生给定的$s$，或者确定没有这样的$w$存在。 

重新表述该过程的一个有用方法是考虑每个 1$w$准确地“传播”其影响力$x$左右步入$s$。 每个位置在$s$就是最多两个位置的或$w$这可以影响它。 

输入大小达到$10^5$跨越所有测试用例，这立即排除了对索引对的任何二次推理。 任何有效的方法对于每个测试用例都必须是线性的，因为即使$O(n \log n)$可以接受但没有必要。 

关键的困难在于映射不是单射的。 单个 1 英寸$s$可以用以下两个位置之一来解释$w$，并且多项选择相互作用。 未经验证而贪婪分配的幼稚方法可能会失败，因为后来的约束可能与早期的分配相矛盾。 

当多个职位处于同一位置时，就会出现微妙的失败情况$s$are 1 but their explanations overlap inconsistently. 例如，如果$s = 1001$和$x = 2$，粗心的策略可能会将它们置于对称位置$w$，但这可能会过度传播并错误地强制额外的或无法满足零约束$s$。 

另一个重要的边缘情况是当位置处于$s$是 0。这意味着两个候选人职位$w$必须为 0。任何构建的方法$w$仅来自于$s$但忽略零约束会高估有效配置。 

## 方法

 一个蛮力的想法是对待每个位置$w$作为二进制变量并模拟所有$2^n$分配，重新计算结果$s$每次。 这显然是不可行的，因为即使对于$n = 40$，状态空间已经有大约一万亿个配置。 稍微更精致的蛮力可能会尝试通过修剪进行回溯，但约束仍然使其呈指数级增长。 

变换的结构是局部的和线性的。 每个位置在$s$仅取决于两个固定位置$w$。 这将问题转化为一个约束系统，其中每个索引$s$对最多两个变量施加 OR 条件$w$。 这正是2-SAT风格的结构，但可以更直接地解决。 

关键的观察是颠倒逻辑。 而不是建造$s$从$w$，我们强制执行条件$w$基于$s$。 如果$s[i] = 0$，那么两者$w[i-x]$和$w[i+x]$（如果存在）必须为 0。如果$s[i] = 1$，那么这些位置中至少有一个必须为 1。 

这立即提出了一个建设性的策略：从最严格的约束开始，修复所有强制零，然后贪婪地确保每一个 1$s$被至少一个可用职位“覆盖”$w$。 一旦满足所有约束，我们就验证一致性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n \cdot n)$|$O(n)$| 太慢了 |
 | 约束构造|$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们构建候选字符串$w$直接地。 

1. 初始化$w$和所有人一样。 这是最宽松的配置，稍后将受到零的限制$s$。 从所有的开始确保我们不会因为过早的限制而错过潜在的解决方案。 
2. 对于每个索引$i$在哪里$s[i] = 0$，消除所有位置$w$这可能有助于$s[i]$。 这意味着设置$w[i-x] = 0$和$w[i+x] = 0$每当这些索引存在时。 
3. 处理完全零后，我们得到了一个部分约束的$w$。 现在我们验证每个位置$i$在哪里$s[i] = 1$确实可以由至少一位活跃贡献者来解释$w$，意思是$w[i-x] = 1$或者$w[i+x] = 1$（在界限内时）。 

如果任何此类位置不满足此条件，则重建是不可能的。 

1. 如果满足所有约束条件，则输出构造的$w$。 

这种排序起作用的原因是零是绝对约束：它们禁止$w$完全。 Ones are existential constraints: they only require at least one supporting position. Handling existential constraints before absolute ones risks locking in incorrect assumptions.

 ### 为什么它有效

 The algorithm maintains a monotonic invariant: every time we process a zero in$s$，我们精确删除中的位置$w$那会违反它。 自从删除一个职位以来$w$只能减少对未来的贡献$s$，我们绝不会意外地为零约束创建误报。 

对于以下位置：$s[i] = 1$，我们只在所有强制拆除后检查可行性。 如果此时不存在候选贡献者，则任何早期选择都无法解决该问题，因为满足 1 的唯一机制是存在至少一个支持 1 的机制。$w$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        x = int(input())
        n = len(s)

        w = ['1'] * n

        # enforce zeros
        for i, ch in enumerate(s):
            if ch == '0':
                if i - x >= 0:
                    w[i - x] = '0'
                if i + x < n:
                    w[i + x] = '0'

        # verify ones
        ok = True
        for i, ch in enumerate(s):
            if ch == '1':
                left = (i - x >= 0 and w[i - x] == '1')
                right = (i + x < n and w[i + x] == '1')
                if not left and not right:
                    ok = False
                    break

        if not ok:
            print(-1)
        else:
            print("".join(w))

if __name__ == "__main__":
    solve()
```构造步骤是通过将整个字符串初始化为 1 来实现的，然后有选择地清零从 0 派生的禁止位置$s$。 这可以避免错过任何潜在的解决方案，因为我们只会在被迫时删除候选人。 

验证步骤至关重要，因为重叠约束仍然可以产生其中某些 1 的配置$s$没有支持地位$w$。 

必须小心边界检查：索引$i-x$和$i+x$访问或修改之前必须进行验证$w$，否则会出现无效的内存访问或错误的逻辑。

 ## 边缘情况

 当零在$s$强行占据一席之地$w$同时需要支持另一个$s$。 例如，如果两个不同的零约束消除了对后一个零约束的两个潜在支持，则该算法会在验证期间正确地最终拒绝该配置，因为没有剩余的支持位置。 

另一个微妙的情况是，当接近边界的指数减少贡献头寸的数量时。 例如，在$i < x$，仅存在右邻居。 该算法自然地处理这个问题，因为它总是在访问之前检查边界$w[i-x]$或者$w[i+x]$，确保没有关于对称性的无效假设。 

最后一种情况是当所有字符都在$s$为零。 算法初始化$w$为所有的，然后将可能对任何零有贡献的每个位置归零$s$，产生有效的全零或部分零配置，它轻松满足所有约束。
