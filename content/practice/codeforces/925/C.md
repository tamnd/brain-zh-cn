 ## 解决方案

 ## 问题理解

 我们得到了一组整数。 我们可以任意重新排序它们。 选择顺序后，我们从零开始计算运行前缀异或，其中每个下一个值是通过将前一个前缀结果与下一个选择的元素进行异或来获得的。 

任务是确定是否存在这样的排序，使得这些前缀异或值形成严格递增的序列。 如果存在这样的排序，我们必须输出一个； 否则我们打印出这是不可能的。 

关键限制是数组的大小最多为 100,000，并且每个值的大小少于 60 位。 这立即排除了任何尝试所有排列的方法，因为这将是大小的阶乘。 即使对排列进行二次检查也是不可行的。 我们正在寻找接近线性或线性算数时间的东西，可能依赖于位结构而不是排序搜索。 

一个微妙的困难是 XOR 在数字顺序方面的表现并不单调。 添加一个大的数字实际上可以减少前缀异或，添加一个小的数字可以增加它。 这打破了“下一个元素越大越好”的天真的直觉。 

典型的失败模式来自于仅基于价值大小的贪婪策略。 例如，按升序或降序取数字可以轻松产生向上和向下的前缀异或序列。 另一个隐藏的陷阱是假设一旦前缀异或增加，它总是可以继续增加，这是错误的，因为异或可以将高位翻转回零。 

## 方法

 强力解决方案将尝试给定数字的每种排列并计算前缀 XOR 序列，检查它是否严格递增。 根据定义，这是正确的，但它需要 n! 排列，每次检查的成本为 O(n)，即使 n 约为 10，也会导致天文数字般的运行时间。 

为了降低复杂性，我们需要了解到底是什么控制着添加一个元素后前缀异或是否增加。 假设当前前缀异或为x，我们尝试添加一个数字b。 新值变为 x XOR b。 它是否大于 x 完全取决于 x 和 b 不同的最高有效位。 在该位，如果结果为 1 并且 x 为 0，则该值增加； 否则它会减少。 

这一观察结果导致了强烈的结构性限制。 设 msb(x) 为 x 的最高设置位的位置。 如果我们检查 XOR 如何影响最高位，我们会发现一些决定性的东西：如果 b 的最高位严格大于 msb(x)，则 x XOR b 必须大于 x，因为结果中新的较高位变为 1，而 x 在那里为 0。 但是，如果 b 的最高位小于或等于 msb(x)，则最高位的不同会使结果更小。 

这意味着在每一步中，我们都被迫选择一个其最高设置位严格大于当前前缀异或的最高设置位的元素。 一旦我们选择了这样一个元素，前缀异或的最高位就变成了该位。 该过程在每一步都严格增加前缀异或的最高位。 

这立即意味着对输入本身的严格限制。 如果有两个数字共享相同的最高设置位，则只能使用其中一个，因为一旦我们使用其中之一，前缀 XOR 就会到达该位，并且不允许再有具有相同最高位的数字。 因此，任何有效的解决方案每个最高位类别最多必须有一个数字。 

一旦这个条件成立，构造就变得确定了：我们按照数字的最高设置位以升序对数字进行排序并输出它们。 每一步都是强制的、有效的。

## 算法演练

 我们完全围绕每个数字的最高设置位构建解决方案。 

1. 对于每个数字，计算其最高有效设置位的索引。 这将每个值压缩为单个结构标签，该标签控制它与 XOR 的交互方式。 
2. 按最高位索引对数字进行分组。 如果任何组包含多个元素，我们立即得出结论：不存在有效的排序。 这是因为从该组中选择一个元素后，前缀 XOR 到达该位，并且永远不能接受具有相同最高位的另一个数字。 
3. 如果所有组最多包含一个元素，我们继续排序。 我们按照最高位索引对所有数字进行升序排序。 这确保了每个下一个选择的数字具有比当前前缀异或严格更高的最高位。 
4. 按此排序顺序输出数字。 

当跟踪前缀 XOR 时，为什么这个顺序是正确的就变得很清楚了。 每一步之后，前缀 XOR 的最高有效位正是最后选择的数字的最高位。 由于我们总是移动到严格较高的位，因此每个下一个 XOR 运算都会将结果中的新的较高位置从 0 翻转到 1，从而保证值的严格增加。 

不变的是，处理完 k 个元素后，前缀 XOR 的最高设置位等于第 k 个所选元素的最高位，并且所有剩余未使用的元素都具有严格更大的最高位。 这可以防止任何减少并确保严格的单调增长。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def msb(x):
    return x.bit_length() - 1

def solve():
    n = int(input())
    b = list(map(int, input().split()))

    groups = {}
    for x in b:
        g = msb(x)
        if g in groups:
            groups[g].append(x)
        else:
            groups[g] = [x]

    for g in groups:
        if len(groups[g]) > 1:
            print("No")
            return

    order = sorted(b, key=msb)

    print("Yes")
    print(*order)

if __name__ == "__main__":
    solve()
```该实现首先使用 Python 的内置 bit_length 计算每个数字的最高有效位。 然后，它按该值对数字进行分组并检查可行性。 关键的决策点是拒绝任何规模大于 1 的组。 

按 msb 排序会产生所需的排列，因为一旦前缀 XOR 达到某个位，在不违反严格增加条件的情况下，剩余的数字就无法再次触及它。 

一个常见的错误是尝试按原始值而不是按位结构排序。 另一个微妙的问题是忘记了最高位的相等已经无效，不仅仅是“不增加”而是严格禁止的。

 ## 边缘情况

 当 n 等于 1 时，会出现极端情况。算法会立即接受它，因为最高位类别之间不存在冲突，并且单个前缀 XOR 是简单严格递增的。 

另一个微妙的情况是多个数字共享相同的最高位。 分组步骤会提前拒绝它。 例如，输入`8 9`两者都有最高位 3，因此在选择一个后，前缀 XOR 达到不存在进一步有效转换的状态，从而使任何排列无效。 

最后，当数字已经按最高位排序时，算法仍然执行分组和排序，但实际上返回相同的序列。 这证实了构造根本不依赖于输入顺序。
