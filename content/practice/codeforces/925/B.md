 ## 解决方案
 ## 问题理解

 我们有一个服务器池，每个服务器都有以资源单位衡量的固定容量。 必须部署两个独立的服务，每个服务可以同时使用多个服务器。 当服务使用多个服务器时，其总负载会平均分配到这些服务器上，因此每个选定的服务器只需要处理服务总需求的一小部分。 

对于有需求的服务$x$，如果它被分配$k$服务器，那么这些服务器中的每一个都应该提供$x / k$单位。 仅当服务器的容量至少达到所需份额时，服务器才能用于服务。 每台服务器可以不使用，也可以指定给这两个服务之一。 

任务是决定是否可以将服务器分成两个不相交的组，以便每个组都可以在平等共享规则下支持其服务，​​如果可以，则输出一个有效的分配。 

关键的难点是相同的集合大小$k$改变了每台服务器的要求，因此组的可行性取决于选择哪些服务器以及选择多少服务器。 

这些约束允许最多 300,000 个服务器，这会立即排除尝试所有子集甚至所有子集对的任何方法。 任何超出的事情$O(n \log n)$或者$O(n \log^2 n)$必须仔细论证。 

一些失败案例自然会出现。 

如果为一项服务分配了太多弱服务器，即使较小的子集可以工作，它也可能会失败。 例如，容量为10的服务器可以支持$x = 20$仅当其单独或适当配对时； 如果我们错误地假设“更多服务器总是有帮助”，我们就会做出错误的贪婪选择。 

另一个微妙的情况是重叠：为第一个服务选择最佳组而不考虑第二个服务可能会阻止第二个服务的所有有效分配，即使存在有效的全局分区也是如此。 这是问题的核心难点。 

## 方法

 强力解释将尝试所有方法将服务器分成两组并检查可行性。 对于每个子集，我们将尝试所有可能的大小并验证其中的每个服务器是否满足阈值$x/k$。 这很快就会爆炸，因为仅分区的数量就是$2^n$，甚至验证单个分割成本$O(n)$，导致不可能的$O(n 2^n)$。 

更结构化的观察来自于按容量对服务器进行排序。 假设我们修复了一项服务并决定准确使用$k$服务器。 如果我们想最大化可行性，我们应该始终选择$k$最强的服务器，因为用更强的服务器替换较弱的服务器只能帮助满足约束。 

按降序排序后$c_1 \ge c_2 \ge \dots \ge c_n$，如果我们取第一个$k$服务器中，限制约束是其中最弱的，即$c_k$。 可行性的条件变为：$$c_k \ge \frac{x}{k} \quad \Leftrightarrow \quad k \cdot c_k \ge x$$这减少了对候选大小的检查$k$到一个单一的不等式。 对于每个服务，我们可以找到最大可行的$k$使用二分查找。 

剩下的挑战是我们必须分配两个不相交的组。 一旦我们为一项服务选择了前缀，另一项服务就必须从剩余的后缀中形成，并且必须在该简化数组上重新计算其可行性。 由于这两种服务都在争夺最强的服务器，因此我们尝试两种顺序：首先分配服务 1，然后分配服务 2，反之亦然。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(2^n)$|$O(n)$| 太慢了|
 | 排序 + 二分查找 + 两次作业 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们按容量降序对服务器进行排序，同时保留原始索引。 然后我们计算每个服务可以从任何前缀获取多少服务器。 

1. 按容量降序对服务器进行排序。 这确保了对于任何选择的尺寸$k$，最好的可能集合是长度的前缀$k$。 
2. 有需求的服务$x$，定义尺寸的可行性$k$作为$c_k \cdot k \ge x$。 我们二分查找最大$k$则满足这个条件。 这样做的原因是增加$k$削弱双方：$c_k$减少同时$k$增加，使可行性变得单调。 
3.让$k_1$是使用完整阵列的服务 1 的最佳可能大小。 
4. 尝试分配第一个$k_1$服务器到服务1。其余服务器形成排序数组的后缀。 
5. 在剩余的后缀上，对服务 2 运行相同的可行性搜索，但将该后缀视为新数组。 如果我们找到一个有效的$k_2$，我们有一个有效的分区。 
6. 如果失败，请交换服务的角色并重复相同的逻辑。 
7. 如果任一排序成功，则输出分区； 否则无法输出。 

### 为什么它有效

 对于每项服务，在所有大小子集中$k$，排序容量的前缀主导所有其他选择。 任何有效的分配都可以转换为使用前缀的分配，而不会降低可行性。 这确保了我们只需要考虑前缀分割，剩下的唯一交互就是如何选择两个前缀之间的分割点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def max_k(arr, x):
    # arr is sorted descending, return max k such that k * arr[k-1] >= x
    n = len(arr)
    lo, hi = 1, n
    ans = 0
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid - 1] * mid >= x:
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1
    return ans

def solve_order(c, x1, x2):
    n = len(c)
    k1 = max_k(c, x1)
    if k1 == 0:
        return None

    # try using k1 for service 1, then service 2 on suffix
    def try_split(k1):
        if k1 == 0 or k1 >= n:
            return None
        c2 = c[k1:]
        k2 = max_k(c2, x2)
        if k2 == 0:
            return None
        return k1, k2

    res = try_split(k1)
    if res:
        return (k1, res[1], 1)

    # swap attempt
    k2 = max_k(c, x2)
    if k2 == 0:
        return None

    def try_split2(k2):
        if k2 == 0 or k2 >= n:
            return None
        c2 = c[k2:]
        k1b = max_k(c2, x1)
        if k1b == 0:
            return None
        return k1b, k2

    res = try_split2(k2)
    if res:
        return (res[0], k2, 2)

    return None

def main():
    n, x1, x2 = map(int, input().split())
    a = list(map(int, input().split()))
    idx = list(range(1, n + 1))

    arr = sorted(zip(a, idx), reverse=True)
    c = [v for v, _ in arr]
    ids = [i for _, i in arr]

    # first order: S1 then S2
    k1 = max_k(c, x1)
    if k1 > 0:
        c2 = c[k1:]
        k2 = max_k(c2, x2)
        if k2 > 0:
            print("Yes")
            print(k1, k2)
            print(*ids[:k1])
            print(*ids[k1:k1 + k2])
            return

    # swap order
    k2 = max_k(c, x2)
    if k2 > 0:
        c2 = c[k2:]
        k1 = max_k(c2, x1)
        if k1 > 0:
            print("Yes")
            print(k1, k2)
            print(*ids[k2:k2 + k1])
            print(*ids[:k2])
            return

    print("No")

if __name__ == "__main__":
    main()
```该解决方案首先对服务器进行排序，以便每个最佳选择都成为前缀问题。 二分查找函数`max_k`捕获可行性条件$k \cdot c_k \ge x$，它对组的大小和其中最弱的服务器进行编码。 

然后，主函数首先尝试分配一个服务，采用其最佳可能的前缀，并检查剩余的后缀是否可以满足其他服务。 如果失败，角色就会互换。 使用排序数组中存储的原始索引重建输出。 

需要注意保持能力和指数之间的一致性； 忘记通过排序携带索引是一种常见的实现错误，它会导致正确的可行性检查但输出无效。 

## 工作示例

 ### 示例 1

 输入：```
6 8 16
3 5 2 9 8 7
```排序：

 | 容量| 索引 |
 | --- | --- |
 | 9 | 4 |
 | 8 | 5 |
 | 7 | 6 |
 | 5 | 2 |
 | 3 | 1 |
 | 2 | 3 |

 为了$x_1 = 8$，可行的前缀大小：

 | k | c_k | k*c_k | k*c_k |
 | --- | --- | --- |
 | 1 | 9 | 9 |
 | 2 | 8 | 16 | 16
 | 3 | 7 | 21 | 21
 | 4 | 5 | 20 |
 | 5 | 3 | 15 | 15

 所以$k_1 = 4$。 

剩余：[3,2]。 为了$x_2 = 16$， 仅有的$k=2$从此开始工作$2 * 3 = 6$失败并且$1 * 3 = 3$失败，所以没有按此顺序解决。 首先分配服务 2，交换成功。 

这说明了为什么顺序很重要：即使存在全局解决方案，对一项服务的贪婪选择也可能会阻止另一项服务。 

### Example 2 (constructed)

 输入：```
5 10 6
6 5 4 3 2
```已经排序了。 

为了$x_1 = 10$,$k_1 = 2$自从$2*5=10$。 剩余的 [4,3,2] 允许$x_2=6$和$k_2=1$自从$1*4=4$失败了，但是$2*3=6$作品。 

该跟踪显示了后缀重新计算的重要性； 删除强大的服务器后，可行性边界发生变化。

 ## 边缘情况

 当一项服务需要所有服务器而另一项服务仍需要至少一台服务器时，就会出现严重的边缘情况。 如果我们贪婪地将所有服务器分配给第一个服务，则第二个服务会立即失败。 该算法会处理此问题，因为后缀变为空并且`max_k`返回零，强制尝试交换。 

另一种情况是，当容量仅仅足以满足大型企业的需求时。$k$。 由于可行性取决于前缀中最弱的元素，因此索引中的任何差一错误$c_k$而不是$c_{k-1}$导致不正确的接受或拒绝。 二分搜索公式通过持续评估来直接防止这种情况$k * c[k-1]$。
