 ## 解决方案
 ## 问题理解

 一群人刚刚完成了一个共享费用事件，每个人都有两个相关的值。 一个值代表如果其他人负责支付账单，他们可以立即贡献多少现金。 另一个值代表如果他们成为支付全部账单并收取其他人现金的人，他们愿意个人承担的最大净成本金额。 

我们被要求选择一个人作为付款人。 如果选择了我，他们会从其他参与者那里收取所有现金，然后使用他们的信用卡支付全额账单。 选择 i 的有效个人成本是总账单减去其他人贡献的现金。 该费用不得超过我允许的个人份额。 

目标是确定是否存在至少一个有效付款人，如果存在，则输出任何此类索引。 

约束最多允许 100,000 人，因此任何解决方案都必须接近线性或线性算数。 通过求和所有其他候选者的贡献来评估每个候选者的二次方法在最坏的情况下将导致大约 10^10 次操作，这远远超出了时间限制。 

当几乎每个人都贡献大量现金但对支付额外费用的容忍度很小时，就会出现一种微妙的边缘情况。 例如，如果一个人的贡献对于可行性至关重要，那么将其作为付款人取消可能会导致其他人无效，即使他们个人看来是可以接受的。 另一个问题是，当所有个体在某种天真的意义上都是“局部有效”时，但一旦考虑到全部总和，在全球范围内没有人能够满足约束。 

## 方法

 核心困难在于，一个人的条件取决于所有其他人现金贡献的总和，而该总和会随着所选候选人的不同而变化。 如果我们独立测试每个人 i，我们需要计算 j ≠ i 时所有 aj 的总和。 对每个 i 的直接重新计算会导致 O(n^2)，因为每次检查都需要扫描所有参与者。 

关键的观察结果是现金总额 S = sum(ai) 是固定的。 如果人 i 付款，他们收取的现金就是 S - ai。 他们的净支付变成 bi 必须至少是 S - ai。 重新排列给出了一个简单的不等式，一旦 S 已知，每个人就可以用 O(1) 的时间来评估该不等式。 

这将问题转化为在单次全局传递后检查每个候选者的单个条件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取所有对 (ai, bi) 并计算所有 ai 值的总和 S。 如果没有人被排除在外，这代表了整个现金池。 
2. 对于每个人 i，想象他们是付款人。 在这种情况下，他们收集的现金是 S - ai，因为其他人都贡献了全部 ai。 
3. 计算个人 i 的有效负担为 (S - ai)。 这是他们在收取现金后必须使用自有资金支付的金额。 
4. 通过验证 (S - ai) ≤ bi 来检查此负担对于 i 人是否可接受。 
5. 一旦一个人满足这个不等式，就输出他们的指数并终止。 
6. 如果扫描所有候选后没有人满足条件，则输出“不可能”。 

### 为什么它有效

 关键的不变量是，非付款人的现金贡献总额仅取决于全局总额减去所选人自己的现金。 这消除了候选人之间的任何互动影响。 每个候选者的可行性仅取决于固定的全局值 S 和它们自己的对 (ai, bi)，因此独立检查它们就足够了。 任何解决方案都不会被遗漏，因为每个有效配置都恰好对应于满足导出的不等式的一个索引。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = []
    b = []
    
    S = 0
    for _ in range(n):
        ai, bi = map(int, input().split())
        a.append(ai)
        b.append(bi)
        S += ai

    for i in range(n):
        if S - a[i] <= b[i]:
            print(i + 1)
            return

    print("impossible")

if __name__ == "__main__":
    solve()
```该解决方案首先汇总所有现金价值以计算总池。 这是至关重要的，因为每次可行性检查都取决于所有其他参与者的总和。 

然后它对所有候选对象进行一次迭代，直接评估导出的不等式。 减法 S - a[i] 表示如果 i 付款则收取的现金。 将其与 b[i] 进行比较会强制执行以下约束：i 的净负担保持在允许的限度内。 

提前返回确保我们在找到任何有效付款人后立即停止，这符合任何有效索引都可接受的问题要求。

 ## 边缘情况

 一种边缘情况是所有 ai 值都很大但所有 bi 值都非常小。 在这种情况下，S 变大，因此 S - ai 对于每个 i 都保持很大，并且条件一致失败。 该算法正确地拒绝输入，因为每个计算的负担都超过了相应的限制。 

另一种边缘情况是当一个人拥有非常大的 ai 和非常大的 bi 时。 假设他们主导了现金池。 那么对于那个人来说，S - ai 就会变小，因为除去他们的贡献会显着减少总数。 该算法正确地识别了该候选者，因为只有他们才容易满足不等式。 

当多个人都有效时，就会出现第三种边缘情况。 由于算法在扫描期间在第一个匹配处停止，因此它可以正确返回任何有效索引，而不需要平局打破逻辑，从而满足问题的要求。
