 ## 解决方案
 ## 问题理解

 我们有一群人共享一套公寓，并且有数量有限的物理钥匙。 随着时间的推移，每个人都会反复离开公寓并返回。 每次这样的外出都是独立的，并由单个间隔描述：出发时间和返回时间。 没有两个事件完全相同地发生，因此我们可以将所有事件视为离开和返回的清晰时间线。 

关键的限制是当某人返回时会发生什么。 如果至少有一个人已经在公寓内，那么返回的人只需按铃即可进入，无需钥匙。 如果当时没有人在里面，那么返回的人必须随身携带钥匙才能打开门。 我们可以在每次旅行中决定出发者是否携带钥匙。 在任何时候，最多 k 个人可以持有钥匙，并且我们必须确保每次“返回空公寓”事件都有人在该次旅行中携带钥匙。 

输出是每次旅行的二元决策：该旅行的人是否应该携带钥匙，或者我们必须报告没有任何分配可以满足所有约束。 

约束 n 和 q 高达 100000，因此任何解决方案在事件数量上都必须接近线性或对数线性。 对所有事件或所有成对的行程进行二次模拟是立即不可能的。 时间很大，高达 10^9，这强烈表明只有事件的顺序很重要，而不是实际的时间值。 

当多人返回且钥匙稀缺时，就会出现微妙的失败情况。 例如，如果 k = 1 并且两个人在不同时间返回空置公寓且内部存在没有重叠，则两人都需要钥匙，但全局只存在一把钥匙。 一个天真的贪婪者在本地为每个人分配密钥可能会错过这种全局耦合。 

另一个边缘情况是某人多次离开和返回。 由于一个人的行程不会重叠，我们可能会想独立对待他们，但密钥是全局共享的，因此在一次行程中分配密钥会影响所有其他行程的可用性。 

## 方法

 强力方法将模拟每次行程的所有可能的密钥使用分配。 每次旅行要么携带钥匙，要么不携带钥匙，因此有 2^q 种可能性。 对于每项任务，我们都会模拟时间线，跟踪里面有多少人，并确保每当公寓变空并且有人返回时，该返回都会得到关键任务的支持。 这很快就变得不可行，因为 q 高达 100000，甚至剪枝也无济于事，因为可行性取决于区间之间的全局相互作用。 

关键的观察是，问题从根本上来说是关于使用 k 个活跃关键载波的有限预算来确保“空间隔返回”的覆盖。 我们不应该考虑每个人或每次旅行，而应该按时间顺序考虑事件并维护一组当前活动的旅行。 行程从出发到返回都是有效的。 如果在返回事件中没有其他人在里面，则必须为该事件分配一个密钥，并且该密钥必须来自当前活动的行程之一。 随着时间的推移，这自然表明了一种贪婪的策略。 

我们处理按时间排序的所有事件。 我们维护目前的内部人员。 我们还维护当前持有密钥的行程。 当返回时，公寓将空出，我们必须确保至少有一次有效旅行被指定为携带钥匙。 如果不存在，我们会为当前活动的行程之一分配一个键。 选择哪个活动行程应携带密钥是核心贪婪决策：我们希望以最小化未来强制分配的方式分配密钥，因此我们将密钥分配给具有最新返回时间的活动行程，因为它保持可用的时间最长。

这将问题转化为具有活动间隔优先级结构的扫描线。

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^q·q) | O(2^q·q) | O(q) | 太慢了|
 | 用贪婪+堆扫线| O(q log q) | O(q log q) | O(q) | 已接受 |

 ## 算法演练

 我们将每次行程转换为两个事件，一个开始事件和一个结束事件，并按时间对所有事件进行排序。 然后，我们按时间顺序模拟该过程，维护当前活动的行程集。 

1. 我们按时间对所有离开和返回事件进行排序，同时保留每次旅行的身份。 这确保我们完全按照更改发生的顺序处理系统。 
2. 我们维护一组已开始但尚未结束的活动行程。 每个活动行程都是持有密钥的候选者。 
3. 我们还维护一个最大堆，该最大堆由当前没有键的活动行程的返回时间键控。 这种结构使我们能够在需要时快速选择一个“最佳候选者”来接收密钥。 
4. 我们设有一个计数器，记录当前公寓内有多少人。 当发生离开事件时，我们将其递减，而当发生返回事件时，我们仅在处理关键逻辑后才将其递增，因为我们需要知道在返回之前公寓是否为空。 
5. 在处理返回事件时，如果处理先前事件后的内部计数表明此返回将发生在空公寓中，那么我们必须确保某些活动行程有可用的钥匙来解锁门。 如果当前没有活动行程持有钥匙，我们将一把钥匙分配给具有最远未来返回的活动行程，将该行程标记为“携带钥匙”。 
6. 当行程结束时，我们将其从活动集中删除，并确保将其从堆中删除。 
7. 如果在任何时候我们需要分配一把钥匙，但已经有 k 个钥匙携带行程处于活动状态，我们将返回不可能。 

它为何有效与一个简单的交换论点有关。 每当必须分配密钥时，选择最近结束的活动行程绝不会恶化可行性，因为它为较早结束的行程保留了灵活性。 任何将密钥分配给较短间隔的解决方案都可以通过将其与较长间隔交换而进行转换，而不会降低有效性，因为较长间隔至少覆盖相同的未来时间跨度，并且在较短间隔的所有情况下仍然可用。 

保持的不变性是，每当系统遇到潜在的“锁定事件”时，我们总是在当前活动的间隔之间进行有效的分配，可以提供密钥，并且我们永远不会超过 k 个同时密钥持有者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, q = map(int, input().split())
    trips = []
    events = []

    for i in range(q):
        p, l, r = map(int, input().split())
        trips.append((p, l, r, i))
        events.append((l, 0, i, p))  # leave
        events.append((r, 1, i, p))  # return

    events.sort()

    # active trips
    active = set()
    has_key = [0] * q

    # max-heap by return time (negative for heapq)
    import heapq
    heap = []

    inside = 0

    # map trip index to (r, p, l)
    info = [(trips[i][2], trips[i][0], trips[i][1]) for i in range(q)]

    for time, typ, idx, p in events:
        if typ == 0:
            # leave
            active.add(idx)
            heapq.heappush(heap, (-info[idx][0], idx))
        else:
            # return event
            # before return, check if inside is zero
            if inside == 0:
                # need at least one key-holder active
                while heap and heap[0][1] not in active:
                    heapq.heappop(heap)
                if not heap:
                    print("impossible")
                    return
                # assign key if possible
                if sum(has_key) < k:
                    # assign to best candidate
                    r_neg, j = heapq.heappop(heap)
                    has_key[j] = 1
                else:
                    print("impossible")
                    return

            # person returns, now inside increases
            inside += 1
            # after return, when they leave later, inside will decrease elsewhere

        # process leave effect on inside after event type if needed
        if typ == 0:
            inside -= 1

    ans = ''.join(str(x) for x in has_key)
    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先构建一个统一的事件列表，以便按时间顺序处理所有活动。 每次行程都作为一个间隔和两个事件进行跟踪。 活动集跟踪当前正在进行的行程，堆存储按最新返回时间排序的键分配的候选行程。 需要延迟删除，因为行程结束时会从活动集中消失，但仍保留在堆中。 

内部计数器会根据事件进行更新，以确定返回是否发生在空置公寓中。 这是键分配的关键触发器。 

通过跟踪当前有多少行程被标记为密钥持有者，密钥约束 k 被全局强制执行。

 ## 边缘情况

 一种重要的边缘情况是当所有人都在外面并且连续发生多次返回时。 该算法必须确保每次必要的“空状态转换”仅进行一次键分配，而不是盲目地每次返回事件。 对于这样的输入：```
2 1 2
1 0 2
2 1 3
```第一次返回可能已经需要一个key，之后系统不再为空，所以第二次返回不会触发另一次赋值。 内部计数器确保了这种行为，因为一旦有人在里面，后续的返回就不会看到空状态。 

另一种情况是，当 k 足够大时，多个间隔可以同时保存键，但只需要一个子集。 基于堆的贪婪确保我们永远不会在较长的间隔可用时浪费短间隔的键分配，因此我们可以避免过早耗尽 k。
