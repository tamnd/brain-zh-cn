 ## 解决方案
 ## 问题理解

 我们给定一个长度的字符串$n$，其中每个位置代表一个红色、绿色或蓝色的灯泡。 唯一可用的操作是选取一个灯泡并“触摸”它，这会立即将其颜色均匀地随机重置为三种颜色中的一种，而与之前的状态无关。 

目标是达到所有灯泡具有相同颜色的状态。 我们可以选择在每一步中触摸哪个灯泡，并且我们希望在最佳策略下最小化所需的预期触摸次数。 

关键的困难在于每次触碰都是随机的，并不能保证改进。 我们本质上是在控制一个具有全局停止条件的独立马尔可夫过程系统：所有组件必须一致。 

约束条件$n \le 100$表明状态空间动态规划或期望 DP 超过计数是合理的，因为配置自然地折叠成由每种颜色的灯泡数量而不是它们的位置定义的等价类。 

天真的解释会独立对待每个灯泡，但耦合来自这样一个事实：只有当所有灯泡匹配时我们才会停止，因此该过程本质上是全局的。 

一些边缘情况暴露了陷阱：

 当$n = 1$，答案始终为零，因为单个灯泡已经满足条件。 

当所有灯泡的颜色已经相同时，例如`ggg`，答案再次为零，因为我们已经处于最终状态。 

误导性案例是这样的`rgb`。 尽管每个灯泡都不同，但最佳策略是不要随意循环颜色； 相反，我们必须考虑如何将系统简化为主导颜色类别。 

核心挑战是局部决策（触摸哪个灯泡）以非线性方式影响全局收敛时间。 

## 方法

 蛮力方法将显式地对所有马尔可夫链进行建模$3^n$配置。 从每个状态，我们考虑灯泡的所有可能选择以及重新着色的所有可能随机结果。 我们计算所有灯泡都相等的任何吸收状态的预期击中时间。 

这是正确的，但立即不可行：即使对于$n = 20$，状态空间变得非常大，每个状态的转换进一步乘以$n$。 状态总数呈指数增长，使得对配置的直接动态编程变得不可能。 

关键的观察是对称性。 灯泡的身份并不重要，重要的是每种颜色存在多少个灯泡。 任何配置都由三元组完整描述$(r, g, b)$和$r+g+b=n$。 这将状态空间从指数减少到$O(n^2)$。 

来自一个州$(r, g, b)$，我们选择某种颜色的灯泡并对其进行统一重新着色。 这会引起这些计数状态之间的转换。 该过程成为有限格上的经典预期命中时间 DP。 

最佳策略是始终在这个压缩状态空间内运行，并计算预期步骤以达到任何计数之一等于的吸收状态$n$。 

这将问题简化为求解所有线性方程组$(r,g,b)$，但我们可以利用转换仅在相邻计数配置之间移动的事实，将其构造为距终端状态距离不断增加的 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解完整配置 |$O(3^n)$状态 |$O(3^n)$| 太慢了|
 | DP 与颜色计数状态 |$O(n^3)$或者$O(n^2)$优化|$O(n^2)$| 已接受 |

 ## 算法演练

 我们用三元组来表示一个状态$(r, g, b)$。 让$E[r][g][b]$表示从该配置开始达到单色状态所需的预期触摸次数。 

1. 识别终端状态。 如果有任何一个$r=n$,$g=n$， 或者$b=n$，则期望值为零。 这些状态很有趣，因为不需要采取进一步的行动。 
2. 对于任何非终止状态$(r,g,b)$，我们通过选择要触摸的灯泡来定义过渡。 最佳选择在期望上是对称的，因此只需分析按比例选择每个颜色类别并求平均值即可。 
3. 假设我们选择一个红色灯泡。 有概率$1/3$，它保持红色，有概率$1/3$它变成绿色，并且有概率$1/3$它变成蓝色。 这会改变状态如下：

 红色计数减少一，然后根据结果三种颜色中的一种增加。 

这会产生转换：

 来自$(r,g,b)$：

到$(r, g, b)$有概率$r/n \cdot 1/3$，

到$(r-1, g+1, b)$有概率$r/n \cdot 1/3$，

到$(r-1, g, b+1)$有概率$r/n \cdot 1/3$,

 选择绿色或蓝色也是如此。 
4. 我们没有明确编码完整的动作选择，而是使用期望的线性。 每一步都会将预期系统简化为相邻状态的组合$(r,g,b)$格子。 
5.我们写出递推式：$$E[r][g][b] = 1 + \sum_{(r',g',b')} P((r,g,b)\to(r',g',b')) \cdot E[r'][g'][b']$$概率来自于均匀地挑选一个灯泡并均匀地重新着色。 
6. 我们通过按照距终端状态距离递增的顺序迭代所有状态来解决该系统，这实际上对应于首先递减的熵配置，因为任何移动变化最多计数为 1。 
7. 我们将所有终端状态初始化为零并放松过渡直到收敛，这是保证的，因为系统在由吸收距离引起的期望排序中是非循环的。 

### 为什么它有效

 该过程形成一个有限马尔可夫链，其吸收态是单色配置。 每个状态都有明确定义的预期命中时间，因为从任何非最终状态开始，总是有正概率接近最终状态。 DP 超计数状态正确地捕获了所有对称等效配置，并且递归执行了对单次触摸的所有可能结果的总期望定律。 由于期望是线性的，因此在聚合状态上求解系统会产生原始随机过程的精确期望值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    r = s.count('r')
    g = s.count('g')
    b = s.count('b')

    # dp[r][g][b]
    dp = [[[0.0] * (n + 1) for _ in range(n + 1)] for __ in range(n + 1)]

    # iterate by decreasing total non-terminal complexity
    for total in range(n, -1, -1):
        for r0 in range(n + 1):
            for g0 in range(n + 1):
                b0 = n - r0 - g0
                if b0 < 0:
                    continue
                if r0 + g0 + b0 != n:
                    continue

                if r0 == n or g0 == n or b0 == n:
                    dp[r0][g0][b0] = 0.0
                    continue

                denom = n
                val = 1.0

                # pick red bulb
                if r0 > 0:
                    p = r0 / n
                    val += p * (
                        (1/3) * dp[r0][g0][b0] +
                        (1/3) * dp[r0 - 1][g0 + 1][b0] +
                        (1/3) * dp[r0 - 1][g0][b0 + 1]
                    )

                # pick green bulb
                if g0 > 0:
                    p = g0 / n
                    val += p * (
                        (1/3) * dp[r0 + 1][g0 - 1][b0] +
                        (1/3) * dp[r0][g0][b0] +
                        (1/3) * dp[r0][g0 - 1][b0 + 1]
                    )

                # pick blue bulb
                if b0 > 0:
                    p = b0 / n
                    val += p * (
                        (1/3) * dp[r0 + 1][g0][b0 - 1] +
                        (1/3) * dp[r0][g0 + 1][b0 - 1] +
                        (1/3) * dp[r0][g0][b0]
                    )

                dp[r0][g0][b0] = val

    print(dp[r][g][b])

if __name__ == "__main__":
    solve()
```该实现将状态空间压缩为每种颜色的计数，这是使问题可解决的关键减少。 三重循环枚举所有有效的$(r,g,b)$州。 当减少一种颜色并增加另一种颜色时，边界处理至关重要，因为如果不仔细检查索引，就会出现无效状态。 

递归直接编码期望方程。 “+1”对应于执行一次触摸的成本。 每个转变的贡献取决于选择该颜色的灯泡并将其重新着色为每个可能结果的概率。 

## 工作示例

 ### 示例 1：`ggg`我们从$(0,3,0)$。 这已经是单色的了。 

| 状态 (r,g,b) | 行动| 下一篇贡献 |
 | --- | --- | --- |
 | (0,3,0) | (0,3,0) | 终端| 0 |

 DP 立即返回 0，因为终止条件在评估任何转换之前触发。 

这证实了已经稳定的配置被正确吸收，而没有不必要的转换。 

### 示例 2：`rgb`初始状态是$(1,1,1)$。 

我们考虑递归的一次迭代：

 | 步骤| r | 克| 乙| 评论 |
 | --- | --- | --- | --- | --- |
 | 开始 | 1 | 1 | 1 | 对称态|
 | 过渡| 变化 | 变化 | 变化 | 每次触摸都会重新分配颜色|
 | 结果 | - | - | - | 期望累积直至吸收|

 从对称性来看，每个动作都保持期望的平衡，但逐渐增加概率质量朝向主导颜色状态。 DP 确保考虑到所有此类对称转换。 

这个例子强调，即使完全混合的状态也能干净地减少到基于计数的转换。

 ## 边缘情况

 一个关键的边缘情况是所有灯泡都相同。 用于输入`rrrr`，状态是$(4,0,0)$。 该算法立即检测终端配置并分配零，而不输入任何重复。 这可以避免 DP 中意外的自转换。 

另一个微妙的情况是双色系统，例如`rrgg`。 开始于$(2,2,0)$，过渡仅涉及红色和绿色计数。 DP 仍然隐含地包括蓝色州，但从未达到这些州。 递归自然地折叠成一个缩小的子空间，并且期望值保持一致，因为无法到达的状态永远不会贡献来自有效转换的概率质量。 

最后的边缘情况是单灯泡场景`r`。 DP 标记$(1,0,0)$作为终端，因此不会评估任何转换，并且结果恰好为零，这与不需要触摸的定义相匹配。
