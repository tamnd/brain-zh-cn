 ## 解决方案
 ## 问题理解

 我们被赋予了一个由两种不同类型的连接连接起来的地方网络。 第一种是一组普通的街道。 这些街道连接所有地方，形成一棵树，每条街道都有正的旅行成本。 因为它们形成一棵树，所以任何两个地方之间都存在一条仅使用街道的简单路径。 

第二种是一组桥梁。 每座桥连接两个地方，成本为零。 任务是构建一个封闭的旅程，在同一地点开始和结束，每座桥梁只使用一次，并且最多允许穿过每条街道一次。 在所有此类有效行程中，我们希望街道贡献的总成本最小，因为桥梁不贡献成本。 

关键的困难在于桥梁迫使我们在它们的端点之间移动，而每次这样的移动都必须通过沿着行道树行走来实现，而不能在整个旅程中重复使用任何街道边缘。 因此，桥端点的连接方式决定了必须消耗多少树。 

约束足够大，任何显式模拟行走的方法都是不可能的。 可能有多达 100,000 个地点和 500,000 座桥梁，因此即使对每座桥梁进行简单的最短路径计算也已经太慢了，并且任何尝试逐步模拟完整游览的方法都将远远超出时间限制。 这促使我们寻求一种解决方案，其中每个桥在预处理后以对数或接近恒定的时间独立处理。 

天真的思维的一个微妙的失败案例是尝试构建完整的桥梁欧拉之旅，然后动态地求和最短路径，同时标记使用的街道边缘。 这种方法会被打破，因为确保“每条街道最多一次”是所有桥梁遍历的全局约束，并且树边缘的局部贪婪重用可能会默默地违反可行性或过高计算成本。 

例如，如果三座桥需要全部经过树中的中心边的路径，则简单的最短路径求和会对该边进行多次计数，即使问题要求它在整个游览中最多使用一次。 然而，声明中的保证意味着有效输入中永远不会出现此类冲突，这允许更简单的分解。 

## 方法

 蛮力的想法是明确构建所需的游览。 人们可以想象构建一个从某个节点开始的图，每当我们穿过一座桥时，我们都必须沿着其端点之间的唯一树路径移动。 我们将模拟这种步行，将每个街道边缘标记为已使用，并拒绝重复使用边缘的移动。 每个步骤都需要在树中找到一条路径并检查边缘使用情况，在最坏的情况下，每个桥都是线性的。 由于桥梁多达 500,000 座，每条路径的长度可能为 100,000，这将变得天文数字般庞大，大约需要 10^10 次操作，这是完全不可行的。 

关键的观察是，问题中的唯一成本来自树的边缘，并且每个桥独立地强制两个节点之间的遍历。 由于树在任何两个节点之间都有唯一的路径，因此桥的成本贡献恰好是该路径上的权重之和。 全局“每条街最多一次”条件已经保证与输入一致，因此我们不需要动态管理边缘冲突。 相反，我们将整个问题简化为计算许多查询的树距离。 

这将问题转化为加权树上的经典离线查询问题。 在对最低共同祖先进行预处理之后，每个桥接查询都可以在对数时间内得到回答。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 带边缘跟踪的模拟游览 | 最坏情况 | O(m·n) O(n) | 太慢了|
 | 基于LCA的距离查询| O((n + m) log n) | O((n + m) log n) | O(n log n) | O(n log n) | 已接受 |

 ## 算法演练

 ### 1. 构建行道树

 我们将 n − 1 条街道边缘存储在带有权重的邻接列表中。 由于图是一棵树，我们可以任意给它求根，例如在节点 1 处。 

### 2. 预计算LCA结构

 我们从根运行 DFS 来计算深度和父指针。 然后我们构建二进制提升表，以便我们可以有效地计算任意两个节点的最低公共祖先。 此步骤确保我们可以以对数时间计算距离。 

### 3.计算树上的距离函数

 对于任意两个节点 u 和 v，它们在树中的距离计算为：深度[u] + 深度[v] − 2 · 深度[lca(u, v)]，其中深度是根据沿根路径的街道权重之和来测量的。 

这个公式之所以有效，是因为从 u 到 v 的树路径分为两条根路径，这两条路径完全重叠到其 LCA。 

### 4. 处理所有桥

 对于每个桥 (u, v)，我们计算 u 和 v 之间的树距离并将其添加到答案中。 由于每座桥必须仅使用一次，因此每次此类移动都是强制性的，并且其成本是固定的。 

### 5.输出总和

 最终的答案是所有这些距离的总和。 

### 为什么它有效

 每座桥都强制在其端点之间进行一次遍历。 因为街道形成一棵树，所以有一种独特的方式来实现这种遍历，并且无论全局排序如何，其成本都是固定的。 街道最多使用一次的约束是通过有效旅行存在的问题保证来满足的，这意味着这些所需的路径不会以强制重用的方式发生冲突。 因此，对独立树木距离求和完全匹配任何有效旅行的总街道成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

LOG = 20

def main():
    n = int(input())
    adj = [[] for _ in range(n + 1)]
    
    for _ in range(n - 1):
        a, b, w = map(int, input().split())
        adj[a].append((b, w))
        adj[b].append((a, w))
    
    parent = [[-1] * (n + 1) for _ in range(LOG)]
    depth = [0] * (n + 1)
    dist_root = [0] * (n + 1)
    visited = [False] * (n + 1)

    def dfs(u, p):
        visited[u] = True
        parent[0][u] = p
        for v, w in adj[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            dist_root[v] = dist_root[u] + w
            dfs(v, u)

    dfs(1, -1)

    for k in range(1, LOG):
        for v in range(1, n + 1):
            if parent[k - 1][v] != -1:
                parent[k][v] = parent[k - 1][parent[k - 1][v]]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a

        diff = depth[a] - depth[b]
        bit = 0
        while diff:
            if diff & 1:
                a = parent[bit][a]
            diff >>= 1
            bit += 1

        if a == b:
            return a

        for k in reversed(range(LOG)):
            if parent[k][a] != parent[k][b]:
                a = parent[k][a]
                b = parent[k][b]

        return parent[0][a]

    def dist(u, v):
        c = lca(u, v)
        return dist_root[u] + dist_root[v] - 2 * dist_root[c]

    m = int(input())
    ans = 0
    for _ in range(m):
        u, v = map(int, input().split())
        ans += dist(u, v)

    print(ans)

if __name__ == "__main__":
    main()
```DFS 初始化深度和根距离数组，其中`dist_root[u]`存储从根到节点 u 的总街道成本。 二元升降台`parent[k][v]`存储每个节点的第 2^k 个祖先，这允许在 LCA 查询期间有效地向上跳转。 

LCA 函数首先通过提升较深的节点来均衡深度，然后同时提升两个节点，直到其父节点匹配。 然后，距离函数使用 LCA 恒等式重建唯一的树路径长度。 

每个桥都是独立处理的，将其树距离准确地贡献给最终答案。

 ## 边缘情况

 一种边缘情况是网桥的两个端点都是同一节点。 在这种情况下，LCA 就是节点本身，距离为零，因此贡献不会影响总和。 该算法自然地处理这个问题，无需特殊的外壳。 

另一种情况是深度倾斜的树木，其中 LCA 提升必须穿越许多层。 二元提升表确保即使在长度为100,000的链状树中，每个查询仍然以对数时间运行。 

另一种情况是在许多查询中重复桥接端点。 由于每个查询都是独立的，并且仅使用预先计算的表，因此完全避免了重复工作，并且不会发生状态突变，因此不存在重复计算或查询之间干扰的风险。
