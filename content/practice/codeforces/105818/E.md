 ## 解决方案
 ## 问题理解

 我们的机器人按速度非递减顺序排列。 对于机器人的每个连续部分，我们想知道它们可以分成的最大组数，以便每个组可以在任何机器人离开轨道之前的不同秒停止。 

具有速度的机器人`a`可以存活到第二个`floor(L / a)`。 如果一组在第二个被射击`t`，该组内的每个机器人必须至少有生存时间`t`。 由于较晚的组被射击较晚，因此速度较快的机器人是危险的，需要较早放置。 

关键的观察是，对于子数组，最佳策略始终将该子数组的前缀作为单独的组。 让`d[i] = floor(L / a[i])`成为机器人的最后一秒`i`。 因为速度是排序的，所以截止日期`d[i]`是非增加的，因此阵列中后面的机器人永远不会比前面的机器人更容易保存。 

对于从以下位置开始的子数组`l`, 长度前缀`k`如果机器人处于位置，则可以工作`l + k - 1`可以存活到第二个`1`，前一个直到第二个`2`， 等等。 这可以写成：`d[i] >= l + k - i`对于该前缀中的每个索引。 重新排列给出：`d[i] + i >= l + k`所以整个前缀必须具有每个值`d[i] + i`至少`l + k`。 

约束条件允许`N`达到`200000`。 检查每个子数组并模拟分组的解决方案需要大约`N^3`在最坏的情况下工作，这远远超出了可能的范围。 即使使用线性扫描检查每个子阵列也会给出`O(N^2)`操作，对于最大的测试来说已经太慢了。 

主要的边缘情况来自于将最佳分组与原始顺序混淆，或者假设整个子数组始终可以分离。 

例如：```
Input:
4 10
1 3 6 10
```答案是：```
17
```最后两个机器人无法分开，因为机器人速度快`10`只存活一秒钟。 总是为每个机器人创建一个组的贪婪解决方案会错误地将此子数组计为具有分数`4`。 

另一个边缘情况是单个机器人：```
Input:
1 100
50
```答案是：```
1
```即使机器人可以存活几秒钟，也只有一个可能的组。 分数计算的是组数，而不是可用秒数。 

第三个常见错误是忘记前缀属性取决于起始索引：```
Input:
3 10
1 10 10
```子数组`[10, 10]`有分数`1`， 不是`2`，因为第二个机器人无法在第二秒被保存。 答案是：```
5
```有效分数为`1, 1, 1, 1, 1`三个单元素和二元素子数组，加上完整的子数组分数`2`。 

## 方法

 一种直接的方法是查看每个子数组，模拟其机器人的截止日期，并贪婪地将最新可能的机器人分配给最早的几秒。 这是正确的，因为这是有截止日期的作业的标准调度思路。 然而，有`N * (N + 1) / 2`子数组，所以即使是`O(length)`每个子数组的计算变为`O(N^3)`。 

重要的观察是，起始位置的答案并不以复杂的方式依赖于正确的边界。 假设我们计算`best[l]`，如果我们采用从以下位置开始的后缀，则可能的最大组数`l`并允许它使用所有剩余的机器人。 然后任何从以下位置开始的子数组`l`与长度`len`有准确的分数`min(best[l], len)`。 

计算`best`， 定义：`value[i] = i + floor(L / a[i])`使用基于一的索引。 有效的长度前缀`k`开始于`i`要求该前缀中的每个值至少为`i + k`。 

从右到左的处理给出了简单的递归。 如果`best[i + 1]`机器人就位后可分离`i`，然后定位`i`仅当其自身值足够大时，才可以将该有效前缀扩展一。 新值是：`best[i] = min(best[i + 1] + 1, value[i] - i)`至少有一个。 

之后，每个起始位置贡献一个简单的算术和。 如果剩余长度为`m`，那么贡献就是`min(best[i], 1) + min(best[i], 2) + ... + min(best[i], m)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N^3) | O(N^3) | O(1) | O(1) | 太慢了|
 | 最佳| O(N) | O(N) | 已接受 |

 ## 算法演练

 1. 计算每个机器人的生存期限。 机器人用`i`， 计算`d[i] = L // a[i]`并存储`value[i] = i + d[i]`。 值转换将分组条件转变为前缀最小条件。 
2. 从右到左处理位置并计算`best[i]`。 最后一个机器人总是可以组成一组，因此初始值为 1。 对于每个较早的机器人，前缀最多可以比它之后开始的最佳前缀长一个，并且它还受到以下限制：`value[i] - i`。 
3. 对于每个起始位置`i`， 让`length = N - i + 1`。 如果`best[i]`至少是`length`，每个可能的前缀长度都是有效的，所以贡献是`length * (length + 1) / 2`。 
4. 否则，第一个`best[i]`长度正常增加，并且每个较长的子数组都保持相同的分数。 将第一部分的算术和与其余部分的常数贡献相加。 
5. 将所有贡献相加并打印结果。 

为什么它有效：

 贪婪分组之所以有效，是因为后来的机器人的截止日期更小，因此可以重新安排任何最佳时间表，以便首先从所选前缀的右侧进行分组。 这意味着唯一重要的是我们可以构建多长的有效前缀。 

递归保留了这个属性。 如果后面有后缀`i`支持`k`组，然后添加机器人`i`只能做长度的前缀`k + 1`如果机器人`i`生存到新的最后一秒。 不再可能有前缀，因为剩余的机器人已经形成最大有效后缀。 因此每一个`best[i]`是正确的，并且最终的求和精确地计算了所有子数组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, L = map(int, input().split())
    a = list(map(int, input().split()))

    best = [0] * (n + 2)

    for i in range(n - 1, -1, -1):
        deadline = L // a[i]
        extend = deadline
        best[i] = min(best[i + 1] + 1, extend)

    ans = 0

    for i in range(n):
        length = n - i
        k = best[i]
        if k >= length:
            ans += length * (length + 1) // 2
        else:
            ans += k * (k + 1) // 2
            ans += (length - k) * k

    print(ans)

if __name__ == "__main__":
    solve()
```数组`best`从右到左计算，因为位置处的值`i`取决于已经计算出的值`i + 1`。 递归仅使用当前机器人的截止时间和下一个后缀结果，因此不需要数据结构。 

贡献计算使用第一个总和的公式`k`正整数。 当子数组变得比最大有效前缀长时，每个额外的机器人都保持分数不变，这就是剩余部分贡献的原因`(length - k) * k`。 

所有计算均使用 Python 整数完成，它会自动处理可能超过 32 位范围的大和。

 ## 边缘情况

 对于单个机器人的情况：```
Input:
1 100
50
```该算法计算`best[1] = 1`。 唯一的子数组的长度为 1，因此贡献为 1。 结果是正确的，因为单个机器人总是恰好形成一组。 

对于同样快速的机器人：```
Input:
4 10
10 10 10 10
```每个机器人都有最后期限`1`。 计算出的`best`价值观都是`1`。 每个起始位置仅贡献一个有效组，因此答案是`4`。 假设总是可以分离相同速度的解决方案会计算过多。 

对于混合情况：```
Input:
4 10
1 3 6 10
```第一个机器人的截止日期很长，可以推迟。 最后一个机器人有截止日期`1`并且必须立即枪决。 递归通过设置有效的前缀长度来捕获这一点`[3, 2, 1, 1]`，最终的总和符合所需的分组行为。
