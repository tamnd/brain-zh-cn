 ## 解决方案
 ## 问题理解

 我们得到一个写在饼干托盘上的整数，我们应该将其视为并排放置的数字序列。 亚伦重复执行相同的操作：他从当前序列中删除一位数字，通过将剩余的数字移位在一起来缩小间隙，然后再次读取结果数字。 如果删除数字会产生前导零，那么这些零也会立即被丢弃，因此该数字始终以其标准化形式进行解释。 

每次删除后，Aaron 都会检查结果是否为质数。 如果是质数，则过程继续； 如果不是，则该过程停止。 第一个数字已经算作起点，因此我们实际上是在计算通过一次重复删除一位数字，从原始数字开始可以获得多少个连续的“有效状态”。 

任务是计算在过程必然失败之前可获得的素数状态的最大数量。 

尽管输入是最大 10^9 的单个数字，但关键结构不是算术而是组合：我们正在遍历所有可能的删除数字的方法，但仅沿着保持数字为素数的路径继续。 

约束 N ≤ 10^9 意味着最多 10 位数字。 这很重要，因为它限制了通过删除可到达的不同状态的总数。 任何状态都只是数字的子序列，因此搜索空间最多为 2^10 = 1024 个候选，并且转换一次删除一位数字，因此总边数很小。 

一个天真的误解是将其视为一个数字过程，并尝试贪婪地或确定性地模拟数字删除。 这会失败，因为不同的删除顺序可以产生不同的中间数，并且我们被要求进行最大可能的运行，而不是单个确定性运行。 

一个微妙的边缘情况是删除数字会产生前导零。 例如，从 103 中删除 1 会生成 03，后者会变成 3。任何按字面处理字符串而不进行规范化的解决方案都会错误地将“03”视为不同的状态或拒绝它。 

另一个边缘情况是单位数素数。 如果数字变成单个数字，如 2、3、5 或 7，则仅当我们仍有数字需要删除时，该过程才会继续，但任何进一步的删除都可能会产生空或无效状态。 

## 方法

 强力解释将考虑从初始数字开始的每个可能的删除序列。 在每一步中，我们都会尝试删除每个剩余的数字并检查所得数字是否为素数。 如果我们递归地进行，这将成为一棵树，其中每个节点最多有 d 个子节点，其中 d 是当前存在的位数。 

由于初始长度最多为 10，因此最坏的情况是探索大约 10！ / 2 条路径在有序删除方面，但更准确地说，状态空间是所有子序列，因此最多 1024 个状态，以及它们之间的转换。 没有记忆的简单 DFS 会重复地重新访问相同的数字配置，特别是因为不同的删除顺序可以产生相同的剩余字符串。 这导致实践中出现指数爆炸。 

关键的观察结果是，该过程的状态完全由剩余的数字及其顺序决定，而不是由我们如何到达那里决定。 这意味着我们可以将每个状态建模为数字位置的位掩码。 从任何掩码，我们都可以转换到少一位设置的掩码。 问题变成有向无环图中的最长路径，其中节点是数字的子集，边表示删除一位数字，约束条件是我们仅遍历解码后的数字为素数的节点。 

由于位数最多为 10，因此我们可以直接评估每个状态的素性，然后按大小递减顺序对子集执行动态规划。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对所有删除序列进行暴力 DFS | O(n!) | O(n) | 太慢了|
 | 每个状态具有素性检查的 DP 子集 | O(2^n * n) | O(2^n * n) | O(2^n) | O(2^n) | 已接受 |

 ## 算法演练

 我们将每个数字子集视为一个状态。 

1. 将输入的数字转换为一串数字，并为每个位置分配一个索引。 这允许我们将任何剩余的配置表示为位掩码。 
2. 预先计算从 0 到 (1 << n) - 1 的所有掩码。对于每个掩码，通过按顺序读取数字并跳过前导零来构造相应的数字。 如果结果字符串变空，我们会将该掩码视为无效而忽略。 
3. 对于每个有效掩码，检查其数值是否为质数。 由于形成的数字最多为 10 位数字，因此高达 sqrt(x) 的确定性素性测试就足够了。 
4. 定义一个 DP 数组，其中 dp[mask] 表示从此配置开始的连续有效素数状态的最大数量。 
5. 对于形成素数的所有掩码，初始化 dp[mask] = 1，因为当前配置本身算作一次出现。 
6. 按照位计数的递减顺序处理掩码，以便在较小的配置之前解决较大的配置。 
7. 对于每个质数掩码，尝试删除每个设置位以形成新的掩码。 如果结果掩码形成有效数字（非空）并且也是素数，则将 dp[mask] 更新为 dp[mask] = max(dp[mask], 1 + dp[next_mask])。 
8. 答案是 dp[full_mask]，其中 full_mask 对应于最初出现的所有数字。 

这种排序起作用的原因是每次转换都会严格减少设置位的数量，因此通过减少位计数进行处理可确保所有依赖关系都已计算出来。 

### 为什么它有效

 每个状态仅取决于严格较小的数字子集。 这会在按大小排序的掩码上产生 DAG。 DP 计算此 DAG 中的最长有效链，其中有效性受到素性约束。 由于每条路径都准确对应一个删除序列，并且每个有效的删除序列都对应一条路径，因此DP涵盖了所有可能性，没有重复或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_prime(x: int) -> bool:
    if x < 2:
        return False
    if x % 2 == 0:
        return x == 2
    i = 3
    while i * i <= x:
        if x % i == 0:
            return False
        i += 2
    return True

def build_value(digits, mask):
    val = 0
    for i in range(len(digits)):
        if mask & (1 << i):
            val = val * 10 + digits[i]
    return val

def solve():
    s = input().strip()
    digits = list(map(int, s))
    n = len(digits)

    size = 1 << n
    valid = [False] * size
    val = [0] * size

    for mask in range(size):
        v = build_value(digits, mask)
        val[mask] = v
        if v > 0:
            valid[mask] = True

    prime = [False] * size
    for mask in range(size):
        if valid[mask]:
            prime[mask] = is_prime(val[mask])

    dp = [0] * size

    masks = list(range(size))
    masks.sort(key=lambda m: bin(m).count("1"), reverse=True)

    for mask in masks:
        if not prime[mask]:
            continue
        dp[mask] = 1
        i = 0
        while i < n:
            if mask & (1 << i):
                nxt = mask ^ (1 << i)
                if valid[nxt] and prime[nxt]:
                    dp[mask] = max(dp[mask], 1 + dp[nxt])
            i += 1

    full = (1 << n) - 1
    if not prime[full]:
        print(0)
    else:
        print(dp[full])

if __name__ == "__main__":
    solve()
```核心实现细节是掩码表示。 每个数字子集都被编码为位掩码，并且转换函数以 O(n) 的时间重建数字。 由于 n ≤ 10，即使对于所有 1024 个状态，此开销也可以忽略不计。 

一个常见的陷阱是无法正确标准化前导零。 构造函数隐式地删除它们，因为我们只将数字累加成整数； 前导零永远不会贡献价值。 

另一个微妙之处是处理空掩码。 它产生值 0，该值无效并且被排除在素性考虑之外。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from math import sqrt

    # inline solution
    def is_prime(x: int) -> bool:
        if x < 2:
            return False
        if x % 2 == 0:
            return x == 2
        i = 3
        while i * i <= x:
            if x % i == 0:
                return False
            i += 2
        return True

    s = input().strip()
    digits = list(map(int, s))
    n = len(digits)
    size = 1 << n

    def build(mask):
        v = 0
        for i in range(n):

                v = v * 10 + digits[i]
        return v

    prime = [v > 0 and is_prime(v) for v in val]

                nxt = m ^ (1 << i)
                if prime[nxt]:
                    dp[m] = max(dp[m], 1 + dp[nxt])

    full = size - 1
    return str(dp[full] if prime[full] else 0)

 ## 边缘情况

 对于输入 101，删除中间数字会生成 11，它是质数，而删除边缘数字会生成 01，它会变为 1，并且不是质数。 正确的实现必须确保 01 被解释为 1 并被拒绝，否则会错误地扩展链。 

对于输入 2，不存在保留非空数字的有效删除。 该算法正确地为初始状态分配 dp[mask] = 1 并返回 1，因为该过程已经从素数开始。 

对于输入 10，删除 0 会得到 1，这不是素数，删除 1 会得到 0，这是无效的。 DP 确保两次转换都失败，因此答案为 0，因为起始数不是素数。 

对于输入 37，两个数字都是质数，但删除一位数字会导致 3 或 7，两者仍然是质数。 DP捕获最长的链是2，达到个位数后就不可能再移动了。
