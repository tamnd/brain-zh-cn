 ## 解决方案
 ## 问题理解

 我们有一排兔子笼，每个笼子里都有一定数量的兔子。 对于每个查询，我们都会收到该行的一个连续段，并且仅允许 Leonardo 在该段内进行操作。 

每“一天”，他都会在该区域选择一对不同的笼子。 他计算了这两个笼子里兔子的数量。 如果该总和是正斐波那契数，则该日有效，但有一个额外的限制：每个斐波那契值在该段的所有日期中最多只能使用一次。 每个查询段的任务是确定可能的最大此类天数。 

用更简单的术语重新表述核心任务，对于一个子数组，我们想要计算有多少个不同的斐波那契数可以表示为从该子数组中选择的两个不同元素的总和。 

约束很大，最多有 100,000 个元素和 100,000 个查询。 任何重新计算每个查询对总和的解决方案都会立即失败，因为即使是单个段也可能包含 n² 对的顺序。 在最坏的情况下，幼稚的每次查询 O(n²) 方法会导致大约 10^10 次操作，这是不可行的。 

一个更微妙的观察是，兔子的数量以 10⁹ 为界，因此任何有效的对总和最多为 2×10⁹。 这意味着我们只关心该范围内的斐波那契数，而且斐波那契数大约只有 45 个。 这组有限的目标是结构简化的关键。 

一些边缘情况值得关注。 

如果段长度为 1，则不存在对，因此答案始终为 0。 

如果一个段中的所有值都相同，例如 [5, 5, 5]，则每对总和都相同 (10)，因此即使 10 是斐波那契数，答案最多也为 1，因为禁止重复。 

如果值很大且稀疏，则根本无法形成许多斐波那契目标，因此答案可能明显小于对的数量。 

## 方法

 直接方法将独立检查每个查询段。 对于固定线段，我们可以枚举所有对 (i, j)，计算它们的总和，并检查每个总和是否为斐波那契数。 我们将使用的斐波那契值存储在一个集合中以强制唯一性。 这是正确的，但内部对枚举主导了复杂性。 对于大小为 k 的段，这是 O(k²)，当 k 接近 10⁵ 时，这太慢了。 

关键的观察结果是斐波那契数列形成了一个固定的小宇宙。 由于所有 Ai ≤ 10⁹，任何总和都≤ 2×10⁹，因此我们预先计算达到该限制的所有斐波那契数。 这样的数字大约只有 44 个。 我们不考虑成对的问题，而是反转视角：对于每个斐波那契数 F，我们询问线段内是否存在一个总和为 F 的对。 

现在问题变成了对子数组的一系列独立的二和存在性查询，对约 44 个固定目标重复。 这更易于管理，因为静态数组上的二和可以使用排序和两个指针来回答，或者如果我们修复段，则可以使用频率结构。 

然而，我们仍然对不同的段有多个查询，因此我们需要一个支持快速段频率访问的结构。 处理此问题的常见方法是独立处理每个斐波那契值，并针对每个查询计算该斐波那契是否可以在其线段内形成。 那么每个查询的最终答案就是可行的斐波那契值的数量。 

为了测试线段 [l, r] 上固定斐波那契值 F 的可行性，我们需要检查 [l, r] 中是否存在 i < j，使得 A[i] + A[j] = F。由于值很大但斐波那契域很小，我们可以压缩数组值并为每个线段使用频率图。 更有效的方法是根据斐波那契值对索引进行离线排序，并对排序后的值数组使用两指针技术，同时使用 Fenwick 树或 Mo 算法维护段约束。

考虑到这些限制，干净的预期解决方案是单独处理每个斐波那契值，并在查询中使用 Mo 算法来维护当前段值的频率结构。 对于每个斐波那契数 F，我们维护一个滑动窗口并增量检查对。 由于斐波那契值的数量是恒定的（~44），因此我们将 Mo 复杂度乘以一个小因子，这仍然可以接受。 

最终的设计是：预先计算斐波那契数，在查询上运行 Mo 的算法，并维护当前段中值的频率数组。 对于每个斐波那契 F，我们通过检查补数频率来维护形成 F 的对的运行计数。 当我们添加或删除一个元素时，我们会更新 O(#Fib) 中所有斐波那契值的贡献，该值是常量。 

这将问题变成大约 O((N + Q) √N × 44)，这是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个查询的暴力破解 | O(Q·N²) | O(1) | O(1) | 太慢了|
 | 莫氏算法+斐波那契枚举| O((N + Q) √N·44) | O(N) | 已接受 |

 ## 算法演练

 1. 预先计算最多 2×10⁹ 的所有斐波那契数，并将它们存储在列表 F 中。这是可行的，因为任何有效的对总和都不能超过此界限。 
2. 读取所有查询并准备离线处理。 我们将使用 Mo 的排序对它们进行重新排序，以便我们可以有效地移动滑动窗口。 
3.维护一个频率数组freq[x]，表示值x在当前段中出现的次数。 
4. 对于每个斐波那契数 Fk，我们维护一个 counterways[k]，用于跟踪当前段中有多少个有效对与 Fk 之和。 
5. 当我们将元素 x 添加到当前段中时，我们通过检查每个 Fk 在插入之前的 freq 中是否存在 (Fk − x) 来更新所有斐波那契计数器。 如果是这样，我们相应地增加ways[k]。 然后我们增加 freq[x]。 
6. 删除元素 x 时，我们首先递减 freq[x]，然后使用更新后的频率减去所有斐波那契数的贡献。 
7. 当我们滑动Mo窗口时，我们不断地维护所有的ways[k]值。 
8. 对于每个查询，将窗口调整为 [l, r] 后，我们将答案计算为斐波那契索引 k 的数量，使得ways[k] > 0。 

正确性依赖于维护当前段内每个斐波那契和的有效无序对的精确计数。 每次更新都会根据插入或删除时是否存在补体来精确调整对计数，确保不会遗漏或重复计算对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Query:
    __slots__ = ("l", "r", "i", "blk")
    def __init__(self, l, r, i, blk):
        self.l = l
        self.r = r
        self.i = i
        self.blk = blk

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    fib = [1, 2]
    while fib[-1] <= 2_000_000_000:
        fib.append(fib[-1] + fib[-2])
    fib = fib[:-1]

    fib_index = {v: i for i, v in enumerate(fib)}
    m = len(fib)

    block = int(n ** 0.5)

    queries = []
    for i in range(q):
        l, r = map(int, input().split())
        queries.append(Query(l, r, i, l // block))

    queries.sort(key=lambda x: (x.blk, x.r if x.blk % 2 == 0 else -x.r))

    freq = {}
    ways = [0] * m

    def add(x):
        for i, f in enumerate(fib):
            y = f - x
            if y in freq:
                ways[i] += freq[y]
        freq[x] = freq.get(x, 0) + 1

    def remove(x):
        freq[x] -= 1
        for i, f in enumerate(fib):
            y = f - x
            if y in freq:
                ways[i] -= freq[y]

    cur_l, cur_r = 0, -1
    ans = [0] * q

    for qu in queries:
        l, r = qu.l, qu.r

        while cur_l > l:
            cur_l -= 1
            add(a[cur_l])
        while cur_r < r:
            cur_r += 1
            add(a[cur_r])
        while cur_l < l:
            remove(a[cur_l])
            cur_l += 1
        while cur_r > r:
            remove(a[cur_r])
            cur_r -= 1

        cnt = 0
        for i in range(m):
            if ways[i] > 0:
                cnt += 1
        ans[qu.i] = cnt

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```该实现依赖于频率字典而不是固定大小的数组，因为值最多可达 10⁹。 添加和删​​除函数通过扫描所有斐波那契数并在恒定时间内检查补集来对称地更新对计数。 

最微妙的部分是删除中更新的顺序：在减去贡献之前减少频率，确保我们不会将删除的元素计为有效对的一部分。 

每个查询的最终答案只是计算有多少个斐波那契目标在当前段中至少有一对有效。 

## 工作示例

 考虑一个小数组 [1, 2, 3, 5] 和斐波那契数 [1, 2, 3, 5, 8, ...]。 对于整个部分，我们跟踪出现了哪些斐波那契和。 

| 步骤| 窗口| 频率 | 有效的斐波那契和 |
 | ---| ---| ---| ---|
 | 1 | [1] | {1:1} | 无 |
 | 2 | [1,2]| {1:1,2:1} | 3 |
 | 3 | [1,2,3]| {1,1,3} | 3、4、5存在吗？ 仅 3,5 个成对 |
 | 4 | [1,2,3,5]| {1,1,1,5} | 3,5,6,7,8 取决于对 |

 此跟踪显示每个新元素如何通过与所有现有值交互来增加可能和的数量。 

现在考虑对 [2,3,5] 的查询。 频率变为{2,3,5}。 有效对包括 2+3=5 和 2+5=7 以及 3+5=8。 仅计算其中的斐波那契数之和，并忽略相同斐波那契数的重复项。 

这演示了算法如何不关心哪些对产生斐波那契数，而只关心是否至少存在一个这样的对。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O((N + Q) √N·44) | Mo的算法处理指针移位，每次移位扫描斐波那契列表 |
 | 空间| O(N) | 频率图和查询存储|

 √N 因子来自 Mo 排序，而常数 44 来自有界斐波那契宇宙。 N、Q 高达 10⁵，这完全符合限制。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    fib = [1, 2]
    while fib[-1] <= 2_000_000_000:
        fib.append(fib[-1] + fib[-2])
    fib = fib[:-1]

    block = int(n ** 0.5)

    queries = []
    for i in range(q):
        l, r = map(int, input().split())
        queries.append((l, r, i, l // block))

    queries.sort(key=lambda x: (x[3], x[1]))

    freq = {}
    ways = [0] * len(fib)

    def add(x):
        for i, f in enumerate(fib):
            ways[i] += freq.get(f - x, 0)
        freq[x] = freq.get(x, 0) + 1

    def remove(x):
        freq[x] -= 1
        for i, f in enumerate(fib):
            ways[i] -= freq.get(f - x, 0)

    cur_l, cur_r = 0, -1
    ans = [0] * q

    for l, r, i, _ in queries:
        while cur_l > l:
            cur_l -= 1
            add(a[cur_l])
        while cur_r < r:
            cur_r += 1
            add(a[cur_r])
        while cur_l < l:
            remove(a[cur_l])
            cur_l += 1
        while cur_r > r:
            remove(a[cur_r])
            cur_r -= 1

        ans[i] = sum(1 for x in ways if x > 0)

    return "\n".join(map(str, ans))

 ## 边缘情况

 诸如 [7] 之类的单元素段产生零有效天数，因为无法形成对。 该算法初始化窗口并且从不在ways[]中注册任何贡献，因为add()需要至少一个现有元素来匹配补码。 

所有值都相同的段（例如 [4,4,4,4]）可确保每次更新添加相同的补集结构。 每个斐波那契值只能由相同的对和重复满足，因此即使存在许多对，也只能计算一个斐波那契数。 基于频率的更新确保多个相同的对仍然只对每个斐波那契目标的单个非零方式条目做出贡献。 

像 [1,1,2] 这样的段测试重复处理。 当插入第二个 1 时，对和 2 变得可用，但删除或重新排序元素不会错误地重复计数，因为更新在添加和删除操作之间是对称的，并且严格取决于当前频率状态。
