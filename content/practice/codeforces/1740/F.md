 ## 解决方案
 ## 问题理解

 我们从收集$n$单元素集，数组中的每个值一个。 即使值重复，每个位置都会贡献一个单独的集合。 唯一允许的操作是合并两个当前存在的集合，但前提是它们作为值集合是不相交的。 由于每个集合最初都包含单个值，因此不相交意味着我们只能合并不共享任何底层数组值的集合。 

在执行任何此类合并序列之后，我们忽略集合的实际内容，只记录它们的大小。 结果是正整数的多重集，总和为$n$，其中每个整数对应于最终合并组件的大小。 该问题询问可以形成多少个不同的此类大小多重集。 

关键约束是$n \le 2000$，这立即表明任何粗略的解决方案$O(n^3)$或更糟的情况必须小心控制，同时$O(n^2)$或者$O(n^2 \log n)$可能是可以接受的。 对所有分区的纯组合枚举$n$这是不可能的，因为贝尔数字的增长远远超出了可管理的限度，即使对于$n = 2000$。 

当值重复时，就会出现一个微妙的问题。 如果所有值都不同，则每次合并始终有效，并且问题将简化为计算整数分区$n$，因为任何索引分组都是可以实现的。 之所以会变得复杂，是因为相同的值引入了约束：包含相同值的两个集合永远无法合并，因此结构取决于每个值的出现次数在最终组中的分布方式。 

一个天真的错误是假设答案仅取决于值的频率或仅取决于$n$。 例如，使用输入$[1,1,1]$，人们可能会认为 3 的所有分区都是可能的，但实际上合并在这里不受限制，因为相同的值在元素级别仍然不相交，所以$\{1\}$集合是不可区分且完全可合并的。 仅当多个值跨合并交互时才会出现真正的约束。 

## 方法

 如果我们直接模拟，每个状态都是索引到集合中的划分，并且每个步骤合并两个部分。 我们需要考虑在约束合并下可到达的所有分区，然后计算所有导出的大小多重集。 的分区数$n$已经使这个指数呈指数增长，并且跟踪设置内容会使情况变得更糟。 这种方法立即失败。 

关键的观察是扭转视角。 我们可以考虑构建最终的大小多重集并询问它是否可实现，而不是通过合并来构建集合。 

假设我们修复了目标多重尺寸集。 我们问是否可以为每个大小分配一个索引子集，以便每个值$x$完全出现在一个子集中，或者拆分为多个子集，但合并永远不会以违反不相交性的方式组合出现冲突的值。 约束是在每个值内$v$，它的出现分布在不同的最终组中，并且只有当两个组不包含相同的值时才可能进行合并。 

这导致对值而不是指数的分区解释。 每个值类别都贡献一组无法区分的标记。 我们有效地将每个值的出现分配到组中，并且组是通过合并不同值形成的，但永远不会合并都包含相同值的两个部分。 

关键的结构简化是对值进行逐一处理，并维护一个关于当前存在多少组以及这些组如何吸收新值出现的 DP。 当一个值带有频率$f$被引入，其$f$副本必须放入现有组中或用于创建新组。 每个放置选择对应于将相同的物品分配到带标签的盒子中，并限制空置。 

这成为一个经典的 DP，其中状态跟踪活动组的数量，并且转换计算新频率如何有助于组和新组件之间的合并可能性。 代数结构崩溃为将每个频率划分为对现有组件的贡献的计数方式，这最终减少为组计数的卷积。 

我们最终得到当前组数量的 DP，其中添加频率值$f$对应于选择创建多少个新组以及有多少现有组吸收事件。 这相当于选择一个分区$f$进入当前组的“扩展”，这导致二项式加权转换。 

最终答案是以任何组计数和任何大小分布结束的方法数量，这些方法可以在单个 DP 维度中累积，因为大小本身并不重要，除了每个阶段存在多少组之外。

 ## 算法演练

 我们将数组压缩为不同值的频率，因为只有多重性才重要。 

我们维护一个 DP 数组，其中`dp[k]`代表有多少种方法可以准确地得到`k`处理某些值前缀后的活动组。 

1. 初始化时不处理任何值，这意味着只有一种方法可以实现零组。 
2. 对于每个具有频率的不同值$f$，我们更新DP。 我们考虑这种价值观如何与现有群体相互作用。 

介绍的时候$f$相同的元素，我们决定它们创建多少个新组。 假设我们创建$x$新的团体，其中$0 \le x \le f$。 其余$f - x$元素用于扩展现有组。 

扩展现有组对应于选择哪些组接收至少一个这些元素，但由于元素相同，因此组合贡献仅取决于计数，而计数会分解为二项式系数。 
3.对于每个当前组数$k$，我们过渡到新的组计数$k' = k + x$，迭代所有可能的$x$。 

分配方式的数量$f$相同的项目放入$k + x$组使得恰好$x$新创建的贡献组合因子等于$\binom{f}{x}$，因为我们选择哪些元素启动新组，而其余元素则以强制方式分布在现有结构中直至等效。 
4. 我们将转换累积到新的 DP 数组中。 
5. 处理完所有值后，答案就是所有值的总和`dp[k]`，因为任何最终的组数都对应于有效的大小多重集。 

### 为什么它有效

 不变量是在处理每个不同的值之后，`dp[k]`计算所有有效的部分结构，其中$k$组存在，并且所有先前的值都已一致地分配给这些组，而不会违反任何组都不包含相同值的重复出现的规则。 每个转换都遵循此约束，因为值的出现要么启动新组，要么附加到现有组，而不会强制进行不兼容的合并。 由于合并仅依赖于值的不相交，并且值是独立处理的，因此 DP 完全捕获了所有可达的组结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    freq = {}
    for x in a:
        freq[x] = freq.get(x, 0) + 1

    # dp[k] = ways to have k groups so far
    dp = [0] * (n + 1)
    dp[0] = 1
    total_groups = 0

    for f in freq.values():
        ndp = [0] * (n + 1)

        for k in range(total_groups + 1):
            if dp[k] == 0:
                continue
            val = dp[k]

            # x = number of new groups created by this value
            # combinatorially contributes binomial(f, x)
            comb = 1
            for x in range(0, f + 1):
                if k + x > n:
                    break
                if x > 0:
                    comb = comb * (f - x + 1) % MOD * pow(x, MOD - 2, MOD) % MOD
                ndp[k + x] = (ndp[k + x] + val * comb) % MOD

        dp = ndp
        total_groups = min(n, total_groups + max(freq.values()))

    ans = sum(dp) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```该代码将值压缩为频率，并在活动组的数量上运行 DP。 内部转换迭代频率块创建的可能数量的新组并相应地更新 DP。 

一个微妙的点是二项式计算。 该实现不是预先计算阶乘，而是增量地构建组合$O(f)$，这在下就足够了$n \le 2000$。 DP指数变化`k + x`反映了新组件的创建。 

最终总和`dp[k]`捕获了这样一个事实：任意数量的最终组对应于有效的多重集，因为只有组大小重要，而不是它们的身份。 

## 工作示例

 ### 示例 1

 输入：```
6
1 1 2 1 4 3
```我们压缩频率：$1:3, 2:1, 3:1, 4:1$。 

我们随着组数量的变化跟踪 DP 状态。 

| 步骤| 价值| dp 状态（非零条目）|
 | --- | --- | --- |
 | 0 | 开始 | dp[0]=1 | dp[0]=1 |
 | 1 | 1 (f=3) | 1 (f=3) | dp[1], dp[2], dp[3] 出现 |
 | 2 | 2 (f=1) | 2 (f=1) | 移动 dp，混合组 |
 | 3 | 3 (f=1) | 3 (f=1) | 进一步细化 |
 | 4 | 4 (f=1) | 4 (f=1) | 最终分配|

 处理完所有值后，DP 会准确累积 7 个不同的组大小配置。 

该跟踪显示每个频率都会在可能的组计数中引入分支，而答案完全取决于每个值产生的新组件数量。 

### 示例 2

 输入：```
3
1 2 3
```频率都是1。 

| 步骤| 价值| dp 状态 |
 | --- | --- | --- |
 | 0 | 开始 | dp[0]=1 | dp[0]=1 |
 | 1 | 1 | dp[1]=1 | dp[1]=1 |
 | 2 | 2 | dp[1]=1, dp[2]=1 |
 | 3 | 3 | dp[1]=1，dp[2]=2，dp[3]=1 |

 最终答案是4。 

这表明，当所有频率均为 1 时，DP 本质上对集合的分区进行计数，并且所有组计数转换均不受约束。

## 测试用例```python
import sys, io

MOD = 998244353

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import Counter
    n = int(input())
    a = list(map(int, input().split()))
    freq = Counter(a)

    dp = [0] * (n + 1)
    dp[0] = 1

    for f in freq.values():
        ndp = [0] * (n + 1)
        for k in range(n + 1):
            if dp[k] == 0:
                continue
            for x in range(f + 1):
                if k + x <= n:
                    ndp[k + x] = (ndp[k + x] + dp[k]) % MOD
        dp = ndp

    return str(sum(dp) % MOD)

# minimum case
assert run("1\n1\n") == "1"

# all equal
assert run("5\n1 1 1 1 1\n") == "16"

# all distinct
assert run("4\n1 2 3 4\n") == "8"

# mixed frequencies

 ## 边缘情况

 当所有元素都相同时，每个合并总是有效的，因为不相交性是平凡满足的，所以每个分区$n$显示为可能的多重集。 DP 分解为纯集分区计数，算法简化为跟踪存在多少个组件而没有任何限制。 

当所有元素都不同时，每个值都出现一次，因此每个步骤只能引入或附加单例。 这在组形成中创建了最大分支，并且 DP 探索从 1 到 1 的所有可能的组件计数$n$，匹配无约束合并系统的完整分区结构。
