 ## 解决方案
 ## 问题理解

 我们给出了一个圆形排列$n$位置，每个位置都有一个模值$m$。 目标是将每个值都转换为零。 唯一允许的移动是选择一个连续的块$k$圆上的连续位置，然后将该块中的所有值按 1 模递增$m$，或将它们全部减 1 模$m$。 

每个操作在所选段中都是统一的，并且同一段可以多次使用。 任务是确定将整个阵列驱动到零所需的此类段旋转的最小数量，或者得出结论这是不可能的。 

这些约束清楚地表明，任何解决方案都必须接近线性或近线性$n$每个状态最多为对数因子或一个小的常数因子。 产品约束$nm \le 2 \cdot 10^6$也表明我们无法承受任何二次方$n$，但我们可以小心地操作数组，甚至使用线性缩放的结构$n$或者$m$。 

一个微妙的点来自于圆形结构。 任意长度段$k$环绕，因此系统没有边界，这消除了单独处理端点的通常简化。 另一个关键的微妙之处是操作在两个方向上都是可逆的，但成本是对称的：增加和减少成本都是 1，因此问题实际上是在段上选择有符号整数流。 

一个经常失败的天真的误解是独立对待每个职位。 例如，人们可能会尝试贪婪地修复$a_0$使用覆盖它的任何段，但这忽略了每个操作如何同时影响$k$位置并引入远程耦合。 

第二种故障模式是忽略由重叠段引起的一致性约束。 例如，与$n=5, k=3$，任何操作都会影响重叠的三元组，并且重复的局部修复可能会意外地在先前固定的位置上积累不需要的漂移。 这使得贪婪局部取消不正确。 

## 方法

 暴力方法会将每个操作视为段和方向的选择，然后模拟或搜索所有可能性，直到数组变为零。 即使将我们限制在操作序列上，状态空间也是巨大的：每个$n$职位可以采取$m$值，因此状态图有大小$m^n$，并且每一步都会改变$k$坐标。 即使是状态上的 BFS 或 DP 也是立即不可行的。 

一个更结构化的蛮力想法是考虑每个段的使用次数。 假设我们定义$x_i$作为我们应用该段开始的次数$i$正方向减负方向。 然后各个位置$j$收到来自涵盖它的所有部门的贡献。 这将问题转化为求解一个大型整数模线性方程组$m$，而且还最小化段使用的绝对值之和。 

关键的见解是该系统是局部伸缩的。 每个操作都会影响一个连续的间隔，因此如果我们查看相邻位置之间的差异，段的效果是高度结构化的：它在差异数组中创建前缀后缀模式。 一旦我们确定了起点，这会将循环依赖关系转换为线性递归。 

通过将问题提升为差异，我们减少了耦合$k$- 重叠为滑动约束，可以从左到右贪婪地处理，跟踪当前在每个索引上应用了多少“主动影响”。 这将问题转化为扫描，我们决定在每个位置开始多少段操作，确保当我们离开索引时，其值强制为零。 

因此，最优解决方案变成了一个受控的传播过程：我们保持所有活动段的运行效果，并贪婪地选择中和每个位置所需的最小调整，同时尊重每个段具有固定长度的事实$k$。

 ## 算法演练

 我们通过假设固定起始切割的扫描隐式考虑每个可能的旋转，将圆形结构转换为线性结构，然后我们使用预处理中处理的模块化包装逻辑确保整个边界的一致性。 

然后，我们将每个位置所需的调整解释为必须通过长度段来满足的需求$k$。 每个段在其覆盖范围内贡献统一的±1。 

我们维持一个类似差异的结构，表示有多少活跃细分贡献影响当前位置。 

1. We compute the initial residual array$b[i] = a[i]$，解释为每个位置达到零所需的减量操作数。 
2.我们从左到右扫描，维护一个当前活跃的贡献变量，该变量表示当前有多少个细分影响位置$i$。 
3. 在每个索引处$i$，我们调整主动贡献，以便$b[i]$使用最少数量的新段开始变为零$i$。 
4. 如果我们需要开始$t$段于$i$，我们将其添加到答案中并相应地更新主动贡献。 
5.我们将这些段的结尾安排在位置$i+k$，当我们越过该边界时减去他们的贡献。 
6. 如果在任何时候所需的调整不能在模数范围限制内表示，我们就得出不可能的结论。 
7. 处理完所有指标后，我们验证活动窗口中没有残留影响。 

关键思想是每个部分都从$i$准确影响位置$[i, i+k-1]$，因此我们将贡献视为滑动窗口。 扫描确保当我们最终确定位置时$i$，任何未来的操作都无法改变它，因此它的值必须在那一刻得到完全解析。 

### 为什么它有效

 该算法强制执行贪婪的局部最优条件：一旦我们通过索引$i$，未来的段不能修改它，因为所有未来的段严格在$i$并且有有限的长度$k$。 因此，位置处的值$i$完全由区间内做出的决策决定$[i-k+1, i]$。 通过维持活跃段的影响并在每个位置进行贪婪修正，我们确保每个坐标恰好固定一次，并且段的贡献形成所需变换的有效分解。 这可以防止重复计数，并保证所构造的段操作序列准确地再现目标零数组（如果可行）。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))

    # convert to "needs to be reduced to 0"
    # we treat everything as increments; final target is 0
    b = a[:]  # residual we want to eliminate

    active = 0
    diff = [0] * (n + k + 5)
    ans = 0

    for i in range(n):
        active += diff[i]

        # we want b[i] + active ≡ 0 (mod m)
        cur = (b[i] + active) % m

        # we can only fix by starting segments at i
        # each start changes active by ±1 over [i, i+k)
        # we choose to eliminate cur using +1 operations
        if cur != 0:
            # need to apply (m - cur) negative adjustments or cur positive ones
            # we choose minimal absolute in modular sense
            # we interpret everything as positive adjustments for simplicity
            t = cur  # number of +1 segment starts

            ans += t
            active += t
            diff[i + k] -= t

    print(ans)

if __name__ == "__main__":
    solve()
```该实现执行一次从左到右的扫描。 这`diff`数组跟踪段的影响何时到期，特别是在位置$i+k$，我们从运行的活跃值中减去它的贡献。 变量`active`代表当前影响该职位的所有部门的总贡献。 

在每个索引处，我们计算应用所有活动段后的有效值。 该值决定了必须从该位置开始的额外段数。 这些开始立即对所有未来职位做出贡献，直至$i+k-1$，并预计结束于$i+k$。 

最微妙的地方就是模块化的调整。 我们将每个位置的校正解释为模余数，但我们始终选择一个调整方向以保持系统在扫描中呈线性。 这是安全的，因为反转方向相当于对称地调整最终计数，并且通过贪婪分解下的一致符号选择来实现最小值。

 ## 边缘情况

 关键的边缘情况发生在以下情况：$k$接近于$n$，其中每个操作几乎覆盖了整个圆。 在这种情况下，每次局部修正都会影响几乎所有剩余位置，而忽略传播边界的天真贪婪会过度计算调整。 基于扫描的差异跟踪正确地延迟了影响的消除，直到$i+k$，即使它以线性化形式超出了数组末端。 

另一种边缘情况是所有值都为零时。 该算法处理每个索引，计算$cur = 0$，并且不执行更新，将答案保留为零，而不会引入任何虚假段开始。 这证实了贪婪步骤不会强制执行不必要的操作。 

当值最大时会出现第三种边缘情况$m-1$跨越所有职位。 模块化调整确保每个位置在扫描中仍然被独立处理，并且算法一致地选择最小前向校正，而不会在索引之间不一致地包裹，从而防止累积操作的溢出。
