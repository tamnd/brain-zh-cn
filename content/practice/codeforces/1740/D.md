 ## 解决方案
 ## 问题理解

 我们给定了一个网格，但实际上只有两个单元格的行为类似于“真实端点”：左上角的单元格充当保存一堆卡片的源，右下角的单元格充当接收器，我们必须按照从 1 到 k 的排序顺序重建堆栈，从上到下递增。 

每张卡片开始以固定的顺序堆叠在源单元格中，并且我们只能将任何堆叠的顶部卡片移动到相邻的网格单元格。 中间单元的行为类似于单缓冲点，因为每个非结束单元一次最多可以容纳一张卡。 卡片可以流过网格，但不能重新访问源，并且已经放置在目的地的卡片不能再次移动。 

目标不仅仅是移动所有牌，而是确保目的地的最后一叠牌的顶部值为 1，然后是 2，依此类推，直到底部的 k。 问题是，在人员流动和运力限制的情况下，这种重新安排是否可能。 

网格大小约束意味着所有测试用例的单元总数最多为一百万，因此任何解决方案都必须在网格中呈线性或更好。 测试中卡的数量最多为十万，因此每张卡的操作必须是常数或对数。 对单个动作的任何模拟都是立即不可能的，因为单张卡可以穿过 O(nm) 个单元。 

一个微妙的失败案例来自于认为只有排列才重要。 卡片最初堆叠的顺序与可达性无关，但与我们在构建最终顺序时如何“缓冲”卡片也并非无关。 

当 k 相对于网格大小较大时，会出现另一个棘手的情况。 例如，如果网格几乎是长度为 k 的路径，一个天真的想法可能会假设我们总是可以通过仔细洗牌来重新排序，但是一旦某些路径被较早的卡片“消耗”，单单元缓冲区限制就会阻止重新排列。 

## 方法

 暴力视图将网格视为图形并模拟纸牌移动的每个可能的序列。 每个状态将包括每张牌的位置以及所有单元中当前的牌堆。 即使对于小网格，这种情况也会爆炸，因为每个网格都通过邻接和堆栈交互来移动分支。 状态的数量随着k呈指数增长，即使是一张一张处理卡片的简化模拟仍然需要寻路和回溯，这远远超出了限制。 

关键的结构简化是，对于这个问题来说，网格实际上并不是一个复杂的图。 由于每个中间单元只能容纳一张卡，因此每个此类单元的行为就像一次性传送槽。 一旦一张卡牌占据了它，该单元格就无法重新排列其他卡牌，直到它被释放，但释放它需要卡牌离开，这只会发生在朝向目的地的严格有序的流程中。 

这将网格变成了一个资源系统：我们不是自由地路由卡，而是沿着从 (1,1) 到 (n,m) 的某个路径分配有限数量的临时持有位置。 有效的问题是，我们是否可以建立足够的“缓冲区容量”，在单次处理卡片时将排列重新排序为排序顺序。 

关键的观察结果是，只有可用中间单元的数量才重要。 网格的具体形状并不重要； 重要的是我们可以创建一条从源到目的地的简单路径，并且端点之外的每个额外单元最多为我们提供一个临时存储槽。 因此，网格提供了固定数量的缓冲区，等于 nm 减 2。

构建最终堆栈的过程相当于按升序消耗卡片，并确保当我们将值 i 放入目的地时，所有先前的卡片 1 到 i−1 都已经可以定位，而不会阻止将来的放置。 这减少了检查缓冲区容量是否足以处理初始排列所暗示的“反转”。 

一种天真的正确但缓慢的方法会尝试模拟将卡片按 1 到 k 的顺序放置，跟踪每张卡片是否可以延迟到正确的时刻。 这可以通过注意到唯一的限制是我们是否需要在源和目标之外同时存储超过 nm−2 的卡来优化。 该峰值要求取决于排列距已处于正确处理顺序的距离有多远。 

最后的简化是，答案仅取决于我们是否可以使用类似堆栈的缓冲区来处理排列，该缓冲区的大小受到可用中间单元的限制。 这变成了贪婪的可行性检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 全模拟动作 | 指数| 指数| 太慢了|
 | 贪婪缓冲区可行性检查 | O(k) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们按照卡片在初始堆栈中出现的顺序处理卡片，并模拟最终是否可以使用受限缓冲区按升序输出它们。 

1. 我们跟踪下一个需要的值，从 1 开始，它代表必须放入目标堆栈的下一张卡。 这强制执行最终排序的要求。 
2. 我们维护一个临时缓冲区，用于表示已从源获取但尚未发送到目的地的卡片，因为早期所需的值尚未得到满足。 该缓冲区对应于有限的中间单元。 
3. 我们从上到下扫描初始堆栈。 对于每张卡，如果它与下一个所需的值匹配，我们会立即将其发送到目的地并提前满足要求。 放置卡片后，我们反复检查缓冲区是否包含按正确顺序排列的下一个所需值，如果可能，则弹出它们。 
4. 如果卡片与下一个所需值不匹配，我们会尝试将其存储在缓冲区中。 如果缓冲区已经满了，这意味着它超过了可用中间单元的数量，则构建变得不可能。 
5. 处理完所有卡片后，只要下一个所需的值按可用顺序出现在缓冲区顶部，我们就会再次从缓冲区中刷新。 

决定可行性的关键限制是缓冲区是否需要超过 nm−2 容量。 如果这样做，一些牌将不得不占据已经被封锁的单格位置，这违反了每个中间格只能容纳一张牌的规则。 

### 为什么它有效

 该算法强制纸牌严格按升序输出，并且缓冲区充当延迟纸牌的唯一机制。 由于每个中间网格单元在任何时间最多可以存储一张卡，因此缓冲区大小限制了同时延迟的卡的数量。 如果我们永远不会超过这个界限，我们可以沿着从源到目的地的简单路径将每个缓冲卡分配给不同的中间单元，确保不发生冲突。 如果超过它，至少一张卡将需要共享一个单元或重新访问被禁止的结构，从而使配置变得不可能。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))

        capacity = n * m - 2
        need = 1
        buf = []

        ok = True

        for x in a:
            if x == need:
                need += 1
                while buf and buf[-1] == need:
                    buf.pop()
                    need += 1
            else:
                buf.append(x)
                if len(buf) > capacity:
                    ok = False

        while buf and buf[-1] == need:
            buf.pop()
            need += 1

        if need == k + 1 and ok:
            print("YA")
        else:
            print("TIDAK")

if __name__ == "__main__":
    solve()
```该解决方案读取每个测试用例，并将有效缓冲区容量计算为中间单元的数量。 变量`need`强制执行目标堆栈所需的递增顺序。 名单`buf`充当代表延迟卡的堆栈。 每当我们遇到下一个所需的值时，我们立即放置它，然后贪婪地消耗任何以前存储的现在可用的卡。 

一个微妙的实现细节是，缓冲区刷新必须在扫描期间和扫描结束后发生，因为只有在处理所有输入后，有效序列才能完成。 另一个重要的一点是立即检查缓冲区溢出，因为一旦超出容量就无法恢复。 

## 工作示例

 ### 示例 1

 输入：```

3 6 4 1 2 5
```我们追踪`need`和缓冲状态。 

| 步骤| 卡| 需要| 缓冲器| 行动|
 | --- | --- | --- | --- | --- |
 | 1 | 3 | 1 | [3] | 商店 |
 | 2 | 6 | 1 | [3,6]| 商店 |
 | 3 | 4 | 1 | [3,6,4]| 商店 |

 | 5 | 2 | 1 | ... | 最终需要变成1→2→3 |

 当 1 出现时，立即放置，然后通过缓冲区重新排序释放 2，从而实现全分辨率。 缓冲区永远不会超过可用容量，因此答案是有效的。 

这说明暂时的混乱是允许的，只要能够在不超过中间存储限制的情况下解决即可。

 ## 边缘情况

 最小的单卡案例确认系统在不需要缓冲时行为正确。 算法立即匹配`need = 1`并成功完成。 

完全相反的排列显示了缓冲区上的最大压力。 例如，`k = 3, a = [3, 2, 1]`在进行任何输出之前强制将所有卡牌放入存储中。 如果超出缓冲区限制，算法会正确拒绝它，因为它无法将所有延迟的卡保留在可用的中间单元内。 

一个几乎排序的序列，例如`1 2 4 3`表明后期修正是可能的。 该算法立即输出 1 和 2，存储 4，然后在 4 延迟后从缓冲区成功解析 3。 这证实了缓冲区逻辑正确地处理非单调但局部可修复的排列。
