 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 每个测试用例中都有$N$女孩们，还有每个女孩$i$被分配了一个段$[l_i, r_i]$。 任务是决定我们是否可以为每个女孩分配一个不同的整数“商店编号”，以便女孩$i$在她允许的段内接收一家商店，并且没有两个女孩共享同一家商店。 

尽管商店的标签是从 1 到$10^9$，只有相对顺序很重要，因为我们实际上不需要构建所有可用的商店。 重要的是我们能否把$N$点，每个间隔一个，没有碰撞。 

约束很大：所有测试用例的间隔总数最多可达$2 \cdot 10^5$。 这立即排除了每个测试用例的任何二次推理。 任何重复扫描所有剩余间隔或使用嵌套循环贪婪地尝试所有分配的方法都会失败。 我们需要更接近的东西$O(N \log N)$每个测试用例或所有测试用例的线性摊销。 

这里常见的失败模式来自于忽略区间结构的贪婪策略。 

一个错误的想法是始终以任意顺序将尽可能小的可用商店分配给每个间隔。 考虑间隔：$[1, 100]$,$[1, 1]$,$[2, 2]$。 

如果我们按输入顺序处理并贪婪地分配，我们可能会将 1 分配给第一个间隔，从而阻塞第二个间隔，即使存在有效分配：将 1 分配给$[1,1]$, 2 至$[2,2]$，和 100 到$[1,100]$。 错误在于独立处理间隔而不考虑紧迫性。 

另一个失败是按左端点排序并贪婪地分配递增的位置。 这也失败了，因为早开始的间隔不一定是最受限制的。 

关键的困难在于每个间隔都有一个由其右端点强加的“类似于截止日期”的结构。 

## 方法

 暴力方法将尝试递归地或通过回溯来分配商店。 在每一步中，我们都会挑选一个女孩，并在她的时间间隔内尝试所有可用的商店。 在最坏的情况下，这会探索指数配置，因为每次分配都会使可用性降低 1，但分支仍然很大。 即使进行了修剪，当间隔严重重叠时，最坏的情况也会很快退化。 

问题的结构提出了一种调度解释：必须为每个女孩分配一个范围内的唯一整数，这相当于将单位长度的作业放在有约束的数轴上。 这与有期限的间隔调度密切相关。 

关键的见解是按照右端点的升序处理间隔。 一旦我们到达某个位置$x$，我们希望将其分配给当时可用的最受约束的间隔，特别是那些仍然可以接受的间隔中最早结束的间隔$x$。 这可以避免在灵活的时间间隔上浪费小端点。 

我们模拟从左到右扫描可能的商店位置，但我们不会迭代所有整数。 相反，我们维护一组已达到左端点的活动间隔，并且始终将下一个可用位置分配给具有最小右端点的间隔。 如果在某个时刻最小右端点小于当前位置，则意味着不再满足区间。 

这将问题简化为使用最小堆的经典贪婪可行性检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力回溯| 指数| O(N) | 太慢了 |
 | 排序 + 最小堆贪婪 |$O(N \log N)$| O(N) | 已接受 |

 ## 算法演练

 我们将每个间隔解释为可用时间$l_i$并到期于$r_i$。 我们模拟分配不断增加的商店索引。 

1. 按左端点对所有区间进行排序。 这使我们能够在他们有资格获得职位时准确地激活间隔。 
2. 维护已排序区间上的指针和按右端点排序的最小堆。 堆代表当前符合分配条件的所有间隔。 
3. 扫描变量`x`代表我们尝试分配的下一个商店索引。 而不是迭代所有整数直到$10^9$，我们只移动`x`当至少有一个活动间隔时。 如果没有有效间隔，我们会跳转`x`到下一个间隔的左端点。 
4. 分配之前`x`，将所有间隔插入堆中$l_i \le x$。 这些是可能使用该位置的间隔。 
5.如果激活后堆为空，则跳转`x`再次向前，因为没有区间可以使用该位置。 这确保我们只处理有意义的职位。 
6. 取最小的区间$r_i$从堆中。 这个时间间隔是最紧急的，因为它对未来的任务有最严格的限制。 
7.如果$r_i < x$，这个区间不能再分配任何有效的商店，所以答案是不可能的。 否则，分配$x$并将其从堆中删除。 
8. 增量`x`并重复，直到所有区间都被分配或出现矛盾。 

第 6 步中的排序选择是关键决策：始终满足最早结束的间隔可以防止阻塞后续的可行性。 

### 为什么它有效

 在任何时候，所有活动间隔都有$l_i \le x$，所以他们有资格获得职位$x$或稍后。 其中，如果我们选择一个具有较大右端点的区间，而忽略较小的右端点，我们就有可能推迟更严格的约束并在以后失去可行性。 任何可行的分配都可以进行转换，以便在每个位置$x$，分配的间隔是最小的间隔$r_i$在仍然可用的那些中，因为在宽松和紧密间隔之间交换分配永远不会破坏有效性，而只能改善松弛。 这种交换论证确保了只要存在解决方案，贪婪选择就可以保留可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        intervals = [tuple(map(int, input().split())) for _ in range(n)]
        intervals.sort()

        heap = []
        i = 0
        x = 1
        ok = True

        while i < n or heap:
            if not heap and i < n and x < intervals[i][0]:
                x = intervals[i][0]

            while i < n and intervals[i][0] <= x:
                heapq.heappush(heap, intervals[i][1])
                i += 1

            if not heap:
                continue

            r = heapq.heappop(heap)
            if r < x:
                ok = False
                break

            x += 1

        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```核心结构是可能的分配的扫描线。 排序的数组确保在正确的时间引入间隔。 堆仅存储右端点，因为插入时左端点已经满足。 变量`x`仅当我们成功分配或必须跳过空白区域时才会前进。 

一个微妙的点是没有活动间隔时的跳跃。 如果没有它，算法可能会不必要地迭代巨大的间隙，直到$10^9$，导致超时。 跳跃保留了正确性，因为无论如何都不能在该间隙内分配任何间隔。

 ## 边缘情况

 第一种边缘情况是所有区间都塌陷为单个点。 用于输入$[1,1], [1,1]$，堆仅包含一个有效的赋值$x=1$，并且第二个间隔立即失败，因为没有第二个位置可用。 

另一种情况是间隔很远的情况。 为了$[1,1], [100,100], [200,200]$，算法反复跳转`x`到下一个可用的左端点。 每个间隔都是隔离的，因此堆空会触发正确的跳过，而不会浪费迭代。 

最后一种情况是严重重叠，例如$[1,10]$重复了很多次。 堆随着所有间隔而增长，并且算法分配从 1 开始的连续整数。如果间隔的数量超过范围并集的长度，堆最终会生成一个间隔$r < x$，在容量耗尽时导致拒绝。
