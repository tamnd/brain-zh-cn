 ## 解决方案
 ## 问题理解

 我们获得了一个通往隐藏 DNA 字符串数据库的二进制接口。 我们唯一能做的就是查询查询字符串中选定的子字符串是否出现在该数据库中的某个位置。 如果它作为任何存储的 DNA 链的子串出现一次，答案就是“存在”，否则就是“不存在”。 一个关键的结构属性是，如果数据库中存在一个字符串，那么它的每个子字符串也被认为存在。 

我们的任务是获取长度为 n 的单个查询字符串，并将其拆分为尽可能多的连续段，使每个段都是“新的”，这意味着它不会出现在数据库中。 这些段必须是不相交的并按顺序覆盖整个字符串。 我们想要最大数量的此类段。 

交互约束很严格：我们最多可以询问 2n 个子串查询，因此我们必须以一种非常受控的方式提取“存在子串与不存在子串”的全局结构，而不需要探索所有 O(n²) 子串。 

重要的约束含义是 n 可以大到 10⁴，因此任何检查所有子串或构建完整子串表的方法都是不可能的。 即使 O(n²) 查询也已经太大了 n 倍，因此解决方案必须小心地只花费 O(n) 查询。 

当存在长子串时，即使不存在较小的子串，也会出现微妙的边缘情况。 因为“present”向下到子串是遗传的，但向上到超弦则不然，所以我们不能假设向前的单调性。 字符串可以不存在，而其所有适当的前缀都存在，反之亦然。 例如，如果存在“ABC”，则“AB”和“BC”也存在，但即使“A”、“B”和“D”独立存在，“ABD”也可能不存在。 除非我们显式验证每个段，否则这会破坏贪婪的子字符串分割。 

关键的困难在于，段的有效性取决于该确切的子字符串是否存在于任何地方，而不是本地字符结构。 

## 方法

 一种简单的方法是考虑字符串的所有可能分段并测试数据库中是否不存在每个分段。 对于每个分段，我们需要使用子字符串查询来验证所有分段。 即使我们固定了一个分区点，验证一个段也至少需要一次查询，而且分区数量呈指数级增长。 这很快就变得不可行。 

一种更结构化的蛮力改进是贪婪地从左向右扩展一段，并在它不存在时停止。 对于每个起始位置 i，我们尝试增加 j 直到子字符串 i..j 不存在，然后在那里剪切。 然而，在最坏的情况下，每次启动仍然需要 O(n) 次查询，导致总体查询次数为 O(n²) 次，这违反了 2n 限制。 

关键的观察是我们实际上不需要知道所有不存在的子串。 我们只需要知道，对于每个位置，我们可以将段延伸多远，同时确保其保持有效，并且我们希望最大化切割次数。 因为数据库在子字符串下是封闭的，所以“存在”子字符串的集合形成了一个结构，其中一旦子字符串不存在，任何扩展名也不存在或与该确切位置无关，但仅此还不够。 真正的技巧是在以下意义上利用单调性：对于固定的左端点 i，随着 j 的增加，一旦我们传递数据库中最长的匹配前缀，子字符串 i..j 只能从存在变为不存在。 这允许二进制搜索或增量扩展，但我们必须将查询总数保持在 2n 以内。

这导致了线性摊销策略：我们维护当前段起点的指针，并在其保持“存在”的同时扩展右边界。 扩展一个字符的那一刻会导致子字符串变得“不存在”，我们会剪切该字符之前的段。 这确保每个位置最多用于两个查询：一个用于测试扩展，一个用于确认边界行为。 

我们本质上是从左到右扫描，保持最大的有效段。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（所有分区/所有子串）| O(2ⁿ) 或 O(n² 查询) | O(1) | O(1) | 太慢了|
 | 具有摊销查询的最佳贪婪扫描 | O(n 查询) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们维护一个指针`i`标记当前段的开始。 我们尝试扩展第二个指针`j`尽可能使得子串`i..j`仍然存在于数据库中。 一旦它消失，我们就完成了该片段。 

1. 初始化`i = 0`和`answer = 0`。 我们处于字符串的开头，尚未形成任何段。 
2. 对于每个位置`i`， 放`j = i + 1`首先查询是否是单字符子串`i..i+1`存在。 这为我们提供了是否有任何段开始于`i`完全可以延长。 如果甚至不存在 length-1 子串，则该段的长度必须为 1。 
3. 扩展`j`向右，而子串`i..j`仍然存在。 每个扩展都通过单个查询进行检查。 我们停在第一个`j`子字符串不存在的地方。 
4. 一旦我们找到第一个不存在的扩展，我们就知道从`i`是`i..j-1`。 我们递增`answer`减 1 并设置`i = j`。 这是安全的，因为从以下位置开始的任何更长的段`i`是无效的，所以我们必须在这里进行切割以最大化段数。 
5. 重复该过程直到`i = n`。 

关键的约束是每次增量`j`只对应一次失败或成功的查询。 每个字符边界最多涉及两个查询，一个确认存在，一个检测不存在，使总查询数保持在 2n 以内。 

### 为什么它有效

 正确性依赖于贪婪的最优子结构：在每个位置`i`，我们选择强制无效扩展边界的最短前缀。 由于将段延伸到第一个“缺失”过渡之外无法使其再次有效，因此立即切割绝不会减少以后可实现的段总数。 数据库属性确保一旦子字符串不存在，其所有进一步的扩展都与该起始位置无关，因此贪婪切割是局部最优和全局一致的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(i, j):
    print("?", i, j)
    sys.stdout.flush()
    return input().strip()

def main():
    n = int(input())
    
    i = 0
    ans = 0
    
    while i < n:
        j = i + 1
        
        # try to extend at least one character if possible
        if j > n:
            ans += 1
            break
        
        # if single char already absent, cut immediately
        res = ask(i, j)
        if res == "absent":
            ans += 1
            i += 1
            continue
        
        # extend while possible
        while j < n:
            res = ask(i, j + 1)
            if res == "absent":
                break
            j += 1
        
        ans += 1
        i = j + 1
    
    print("!", ans)
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```该代码遵循贪婪扫描策略。 功能`ask(i, j)`包装交互式查询并确保每次请求后刷新。 主循环保持左边界`i`并尝试突破正确的界限`j`在子字符串仍然存在的情况下尽可能远。 

每个段的第一个查询会检查最小扩展是否有效。 当最佳段被迫长度为 1 时，这可以防止不必要的扫描。内循环递增`j`并且总是测试`i..j+1`，确保我们检测到第一个故障点。 当发生故障时，该段结束于`j`。 

一个常见的实施陷阱是逐一处理`j`。 查询使用半开索引`[i, j)`，因此每个扩展都必须与我们检测到“不存在”的时刻仔细对齐。

 ## 边缘情况

 对于长度为 1 的字符串，算法立即查询单个子字符串，并将其切割为独立段或确认其为唯一有效段。 不存在指针移动不正确的可能性，因为`i`和`j`重合。 

对于每个子字符串都不存在的情况，每个长度为 1 的查询都返回“不存在”，因此每个字符都会立即被剪切。 该算法产生 n 段，每次迭代都会递增`i`正好 1，防止无限循环或跳过索引。 

对于每个子字符串都存在的情况，扩展循环运行直到字符串末尾并恰好生成一个段。 由于没有出现“缺席”响应，`j`达到`n`最后的切割发生在末端边界，将整个字符串覆盖在一个片段中。
