 ## 解决方案
 ## 问题理解

 我们得到一个连通的无向图$n$交叉点。 每条边代表两个交叉路口之间的一条街道$u$和$v$，每条街道都包含一连串的线性房屋。 我们唯一的灵活性是方向：我们可以决定沿着边缘的房屋编号是否从$u \to v$或来自$v \to u$。 

约束是局部的，但在顶点处表达。 在任何十字路口，多条街道相交，每条街道恰好贡献一个与该十字路口相邻的端点房屋。 该规则规定，接触同一十字路口的两栋房屋不得使用相同的号码。 由于顶点对每个入射边仅看到一个数字（端点门牌号），因此这意味着所有入射边必须在该顶点分配不同的端点标签。 

每条边的长度$h$提供端点标签$1$和$h$。 如果我们将一条边定向为$u \to v$， 然后$u$收到标签$1$和$v$收到标签$h$。 反转交换它们。 

因此，任务变成为每条边选择一个方向，以便在每个顶点，所有入射边都产生成对不同的端点值。 

输入大小可达$10^5$边，因此任何解在边数上都必须是线性的或接近线性的。 二次或偶数$O(n \log n)$在密集图中，反复重新访问每个顶点的边的方法会太慢。 

当与一个顶点相关的多条边具有相同的长度时，会出现一个微妙的问题$h$。 如果两条这样的边都朝向相同的端点配置，则它们可能会在顶点处产生相同的端点编号，从而立即违反约束。 另一个隐藏的陷阱是循环：局部贪婪选择可能会围绕循环不一致地传播，并在返回起点时产生矛盾。 

## 方法

 如果我们忽略效率并局部思考，则每条边都有两种可能的状态，并且每个顶点对其事件选择施加唯一性约束。 暴力尝试会尝试所有$2^m$方向和检查有效性，这显然在微小的图表之外是不可行的。 

更结构化的强力方法是回溯：逐条指定方向，并为每个顶点维护指定端点值的多重集。 当冲突发生时，原路返回。 在最坏的情况下，这仍然探索指数空间，因为每条边都会使分支因子加倍，并且约束仅在冲突出现时才进行后期修剪。 

关键的观察结果是，约束完全基于顶点，并且仅依赖于沿邻接的类似奇偶校验的一致性，而不依赖于全局值$h$。 每条边恰好贡献两个端点标签，并且每个顶点必须为每个事件边“消耗”一个唯一的标签。 如果我们将条件重新解释为端点上的匹配样式一致性问题，则该结构变得易于管理。 

我们不考虑数值，而是关注这样一个事实：每条边在其端点处施加两个不同的“角色”，并且每个顶点必须为关联边分配不同的角色。 这减少了定向边缘，以便在每个顶点处，没有两个选定的“低”端点发生碰撞。 然后，图结构强制执行一种传播规则：一旦我们决定一条边的方向，相邻边通常会受到约束，并且可以通过连接组件之间的奇偶校验式传播来检测矛盾。 

这导致了一种图遍历方法，我们在确保局部一致性的同时分配方向，并且每当出现冲突时，我们就得出不可能的结论。

 | 蛮力 |$O(2^m \cdot n)$|$O(n)$| 太慢了|

 ## 算法演练

 1. 构建邻接表，存储每条边的端点、索引和长度$h$。 我们还跟踪每条边所选择的方向。 
2. 我们维护顶点的访问状态和用于遍历的队列或堆栈。 每个顶点将接收由已经定向的边引起的约束。 
3. 从任意顶点开始，为一个入射边指定任意方向，并将两个端点推入处理结构中。 初始选择充当定义所有后续一致性决策的种子。 
4. 处理顶点时$v$，检查所有尚未定向的入射边。 对于每个这样的边$(v, u, h)$，决定其方向，以便$v$不重复使用冲突的端点标签。 由于每个顶点必须具有不同的端点值，因此只要两个端点值之一已在以下位置“使用”，就会强制方向：$v$。 
5. 当边定向时，将约束传播到其另一个端点。 如果目标顶点对该边已经有冲突的分配，我们会检测到不一致并停止。 
6. 继续，直到处理完从一开始可到达的所有顶点。 如果存在多个组件，我们会重复，但图是相连的，所以一次运行就足够了。 
7. 如果没有出现矛盾，则按输入顺序输出为每条边选择的方向。 

### 为什么它有效

 该算法强制执行局部单射不变量：在任何时刻，每个顶点都维护一组由已定向的事件边引起的端点值，并且任何值都不会插入两次。 因为一旦定向，每条边都会为每个端点贡献一个值，因此任何未来的定向决策仅受已经固定的值的约束。 如果发生冲突，则意味着两个不同的传播路径在顶点处强制使用相同的端点值，这在任何全局分配下都是不可避免的，因此不存在有效的方向。 相反，如果该过程在没有冲突的情况下完成，则每个顶点都收到成对不同的端点标签，全局满足条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    edges = []

    for i in range(n):
        u, v, h = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v, h))
        g[u].append((v, i))
        g[v].append((u, i))

    # orientation: 0 means u->v as stored, 1 means v->u
    orient = [-1] * n
    used = [set() for _ in range(n)]

    sys.setrecursionlimit(10**7)

    def dfs(v):
        for u, idx in g[v]:
            if orient[idx] != -1:
                continue

            a, b, h = edges[idx]

            # decide direction based on current vertex v
            if v == a:
                from_v, to_v = a, b
                dir0 = 0
            else:
                from_v, to_v = b, a
                dir0 = 1

            # try orient from_v -> to_v
            if h not in used[from_v]:
                orient[idx] = 0 if from_v == a else 1
                used[from_v].add(h)
            else:
                # reverse orientation
                if h in used[to_v]:
                    print("impossible")
                    sys.exit(0)
                orient[idx] = 1 if from_v == a else 0
                used[to_v].add(h)

            dfs(to_v)

    dfs(0)

    print(*orient)

if __name__ == "__main__":
    solve()
```对于每个顶点，该实现维护已被用作端点标签的房屋长度。 这是约束的直接编码，即任何两个入射边都不能贡献相同的端点号。 

DFS 确保边缘方向一旦固定，就不会再被重新访问。 关键的决策点是方向选择：如果沿默认方向定向边会在当前顶点引入重复值，则算法会翻转它，前提是翻转不会在另一个端点产生冲突。 如果两个方向都违反约束，则配置是不可能的。 

一个微妙的实现问题是确保边缘只被处理一次。 这是通过以下方式处理的`orient`数组充当边缘的已访问标记。 另一个问题是递归深度，因为$n$可以很大； 递归限制相应增加。

 ## 边缘情况

 关键的边缘情况是高度顶点，其中许多入射边共享相同或重叠的约束。 例如，如果一个顶点连接到多条具有相同长度的边，则任何方向最终都会强制在该顶点处重复端点值。 该算法立即检测到这一点，因为`used`在处理每条边时，为该顶点设置的值会拒绝重复项。 

另一个边缘情况是局部贪婪决策传播不一致的循环。 在三角形中，选择满足两条边的方向可能会迫使第三条边进入违反一个端点处已使用端点的方向。 DFS 传播确保在处理最终边缘时检测到此类矛盾，从而防止出现无声的不一致。 

最后一个微妙的情况是图是树。 在这种情况下，不存在产生冲突传播的循环，并且 DFS 总是成功，因为每条边都引入了新的结构。 该算法将沿着遍历一致地分配方向，并且每个顶点将通过构造维持不同的端点值。
