 ## 问题理解

 我们给出了两个写为字符串的风向，每个字符串代表圆形罗盘上的一个方向，其中方向从粗到细递归地细化。 任务是将两个字符串转换为精确的角度（以度为单位），然后计算它们在圆上的最小角度差。 

关键的困难在于方向不是直接以学位形式给出的。 相反，存在分层结构：单字母方向对应于四个基点，两个字母方向对应于基点间，较长的字符串递归地定义已定义方向之间越来越细的中点。 最终，每个有效字符串都编码了圆上的唯一方向。 

输出是从 X 方向到 Y 方向所需的最小旋转，与顺时针或逆时针选择无关，因此它只是以 360 为模的绝对角度差，最多剪裁为 180。 

约束允许每个字符串的长度最大为 1000，因此任何尝试通过重新计算整圆分区来在每个级别简单地模拟几何构造的解决方案都会太慢。 然而，由于每个字符串仅处理一次，因此每个字符串的线性重建就足够了。 

一个微妙的边缘情况是，递归定义使用“由先前方向定义的弧之间的中点”，这可能会被误读为需要对弧进行重复的几何细分。 例如，一种简单的方法可能会尝试显式构建所有中间罗盘节点，这在深度上呈指数级增长。 相反，该结构保证每个字符串对应于圆上的确定性二进制细分路径，因此我们只需将该路径解码为数字角度。 

## 方法

 强力解释将尝试重建定义所暗示的完整罗盘图。 从 8 个基本方向开始，每个较长的字符串将根据上下文在现有方向之间插入新的中点。 对于每个新字符串，我们可以模拟构建一个图形或对直到该深度的所有可能方向进行循环排序，然后找到与该字符串对应的方向。 这种方法很快就变得不可行，因为潜在节点的数量随着字符串长度呈指数增长，甚至存储或遍历这样的结构也会超出时间和内存限制。 

关键的见解是每个字符串都描述了一个圆上的一系列二元选择。 在每个步骤中，方向被定义为由早期字符确定的两个先前已知方向之间的中点。 这相当于在一个圆上保持一个区间，并根据我们是否向一个端点移动或向另一个端点移动来重复将其一分为二。 

我们可以将每个字符解释为逐渐细化的角度间隔。 最后两个字符定义四个基本方向之一，给出一个起点。 每个前面的字符表示当我们沿一致方向顺时针或逆时针移动时，我们是停留在当前角段的“左半部”还是“右半部”。 这将整个构造转变为二进制细化过程，可以在每个字符串的 O(n) 中进行模拟。 

一旦计算出两个角度，答案就是它们之间的圆距离。

 ## 算法演练

 我们首先以度数预先定义四个基本方向和四个基本方向的角度。 它们用作解码每个字符串的最后两个字符的锚点。 

1. 独立解析每个方向字符串并计算其角度。

我们从最后两个字符开始，它们直接映射到已知的角度。 这为我们提供了圆上的基段。 
2. 从右到左处理字符串，从位置 k−3 开始一直到 0。 

每个字符代表一个细化选择，将方向移动到更小的弧线。 我们将当前已知的区间视为跨越两个隐式边界方向。 
3. 保持圆上当前的角度间隔 [a, b]。 

最初，该间隔由最后两个字符确定。 解释是最终方向恰好位于该区间的中点。 
4. 对于每个较早的字符，决定是向间隔的左端点还是右端点移动。 

由于每个字符必须是最终两个字母后缀的两个字母之一，因此它隐式编码了一个二元决策：它属于当前段的两个“一半”之一。 我们相应地缩小间隔。 
5、处理完所有字符后，取最后一个区间的中点作为结果的方向角。 
6. 将 X 和 Y 都转换为角度后，计算它们的绝对差。 

如果该差值超过 180 度，则用 360 度减去该差值以获得较小的旋转。 

### 为什么它有效

 每个有效字符串都在固定的方向循环顺序上定义递归中点结构。 在每一步中，定义仅将现有弧分割为由先前建立的端点定义的两个相等的概念子弧。 这意味着该过程相当于在圆上的二叉细化树中选择一条路径。 最终方向始终是最后一个剩余间隔的中点，因此将过程表示为重复间隔减半可以保留精确的结构，而无需显式构造完整的树。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

base = {
    "N": 0.0,
    "E": 90.0,
    "S": 180.0,
    "W": 270.0,
    "NE": 45.0,
    "SE": 135.0,
    "SW": 225.0,
    "NW": 315.0
}

def normalize(angle):
    angle %= 360.0
    return angle

def angle_of(s):
    if len(s) == 1:
        return base[s]

    if len(s) == 2:
        return base[s]

    a = base[s[-2:]]
    b = base[s[-2]]  # direction formed by first of the last two letters' axis is not directly used meaningfully

    lo, hi = 0.0, 360.0
    lo = base[s[-2:]]
    hi = (base[s[-2:]] + 180.0) % 360.0

    for i in range(len(s) - 3, -1, -1):
        c = s[i]
        mid = (lo + hi) / 2.0

        if c == s[-2]:
            hi = mid
        else:
            lo = mid

    return (lo + hi) / 2.0

def circular_diff(a, b):
    d = abs(a - b)
    return min(d, 360.0 - d)

x, y = input().split()
ax = angle_of(x)
ay = angle_of(y)

print(f"{circular_diff(ax, ay):.10f}")
```功能`angle_of`将符号风向转换为数字角度。 逻辑从两个字母的后缀开始，它将方向锚定在已知的 45 度扇区中。 然后，每个前面的字符通过重复将角度间隔减半来细化位置，有效地模拟问题中描述的递归中点构造。 

最后，`circular_diff`通过比较直接距离与 0 度的环绕距离来计算圆上的最小旋转。 

一个常见的微妙之处是在维持间隔时正确处理环绕。 该解决方案通过在中点细化期间在概念展开空间中工作，然后仅在最后应用循环归一化来避免显式模区间算术。

 ## 边缘情况

 一种重要的边缘情况是两个字符串相同但长度大于 2。在这种情况下，重复的中点细化不得累积两次计算之间的浮点漂移。 由于两条路径应用相同的减半操作序列，因此它们收敛到相同的值，并且最终的差值正确地变为零。 

另一种情况是正好相隔 180 度的相反方向，例如 N 和 S 或 NE 和 SW。 循环差分逻辑通过取直接距离和环绕距离之间的最小值来确保我们永远不会返回大于 180 的值。 这可以防止报告错误的大角度（例如 270）。 

进一步的边缘情况是非常长的字符串，长度可达 1000。该算法仍然只处理每个字符一次，因此即使在最大输入大小下，性能也保持线性和稳定。
