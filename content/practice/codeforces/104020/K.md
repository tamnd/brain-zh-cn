 ## 解决方案
 ## 问题理解

 我们有一个矩形网格，其中每个单元格都包含一个从 1 到$h \cdot w$。 将网格视为定向导航系统：从任何当前单元格开始，访问者不会随机移动或沿着最短路径移动，而是遵循取决于固定目标单元格的确定性规则。 

访客从选定的信息亭开始。 对于被视为目的地的每个其他单元格，访问者重复一步一步地移动。 在每一步中，他们都会查看四个相邻的单元格，并选择标签最接近目标单元格标签的单元格。 如果多个邻居同样接近，则通过选择标签更接近当前单元标签的邻居来打破平局。 仅当到达目标单元格时，该过程才会停止，否则它可能会永远继续下去或陷入循环。 

任务是选择自助服务终端位置，以便在此规则下可以到达每个目标单元格，并且在所有有效的自助服务终端位置中，最小化到达任何目的地所需的最差步数。 如果没有一个自助服务终端可以到达所有目的地，那么答案是不可能的。 

网格大小最多为 40 x 40，因此最多有 1600 个单元格。 这足够小，我们可以负担单元数量为二次甚至三次的算法，但是任何试图以简单的方式独立模拟所有源和所有目的地的任意路径的算法都可能面临高达数十亿次转换的风险。 

当确定性运动创建不包括目的地的循环时，就会出现微妙的失败情况。 例如，如果在一个区域中的每个单元格中，“最接近目标的标签”规则不断在几个单元格之间跳动，那么即使网格按通常意义上的方式连接，访问者也永远不会到达目的地。 在这种情况下，任何可以到达该目的地的区域的自助服务终端都将变得无效。 

另一个棘手的情况是可达性取决于目的地。 单元格可以到达目的地 10 下的单元格 10，但无法到达目的地 20 下的单元格 20。这破坏了单个静态图的任何想法； 相反，每个目的地都会在同一网格上产生不同的有向图。 

## 方法

 一种直接的方法是修复一个信息亭，然后针对每个目标单元，逐步模拟该过程。 每个动作都是$O(1)$，但单个模拟可能会无限循环或在到达目的地之前访问许多状态。 对所有对的自助服务终端和目的地执行此操作会导致粗略的结果$O(n^2 \cdot n)$最坏情况下的行为，当$n = 1600$。 

关键的观察结果是，对于固定目的地，移动规则变得完全确定：每个单元格都有一个确切的下一步输出。 这将网格变成分别针对每个目的地的功能有向图。 在这样的图中，目的地的可达性相当于目的地是否位于同一功能组件的可达集中。 我们可以通过反转边并从目的地运行 BFS 来计算可以到达目的地的所有节点。 

一旦我们知道，对于一个固定的目的地，哪些起始位置可以到达它以及需要多少步，我们就可以独立地对每个目的地重复此操作。 然后，信息亭选择就变成了一个简单的聚合问题：我们需要一个可以到达所有目的地的节点，并且在这些节点中，我们最小化所有特定于目的地的 BFS 结果之间的最大距离。 

这减少了从动态模拟到构建的问题$n$函数图和运行$n$BFS遍历，这是可行的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每对的强力模拟 |$O(n^3)$最坏的情况|$O(1)$额外 | 太慢了|
 | 每个目的地的功能图 BFS |$O(n^2)$|$O(n^2)$| 已接受 |

 ## 算法演练

 对于每个单元格，我们首先将其位置转换为索引并存储其标签。 这允许恒定时间访问坐标和值。 

然后我们将每个单元格作为潜在的目的地进行处理。 对于固定目标单元格$t$，我们构建一个有向图，其中每个单元格$u$恰好有一个由移动规则定义的传出边缘。 

然后我们计算该图的反向邻接列表，因为我们想要从目的地向后传播可达性。 

### 步骤

 1. 对于每个目标单元格$t$，计算每个单元格$u$它的下一个单元格$next(u, t)$通过检查最多四个邻居并应用距离规则来打破平局。 
2. 构建一个存储所有内容的反向图$u$这样$next(u, t) = v$。 
3. 从以下位置开始运行 BFS$t$在这个反向图中计算所有可以到达的节点$t$，以及到的最短距离$t$。 
4. 将这些距离存储在表中$dist[t][u]$，其中它表示需要多少步$u$达到$t$，如果不可能则为 -1。 
5. 处理完所有目的地后，迭代每个可能的信息亭$s$。 
6. 检查是否$dist[t][s]$为所有目的地定义$t$。 如果没有，则丢弃$s$。 
7. 对于有效的信息亭，计算最大值$dist[t][s]$全面的$t$。 
8. 选择最小化该最大值的信息亭。 

### 为什么它有效

 对于每个目的地，移动规则定义了确定性函数图。 反转边将可达性转换为未加权图中的单源最短路径问题。 BFS 正确计算最少步数，因为每条边都对应于一次移动。 

信息亭的全局有效性条件只是所有每个目的地可达集合的交集。 如果自助服务终端即使在一个目的地发生故障，也意味着在该目的地的功能图中，它位于目标节点的吸引力盆地之外。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

h, w = map(int, input().split())
n = h * w

grid = []
pos = [None] * (n + 1)

for i in range(h):
    row = list(map(int, input().split()))
    grid.append(row)
    for j, v in enumerate(row):
        pos[v] = (i, j)

dirs = [(1,0), (-1,0), (0,1), (0,-1)]

def inside(x, y):
    return 0 <= x < h and 0 <= y < w

dist = [[-1] * (n + 1) for _ in range(n + 1)]

for t in range(1, n + 1):
    tx, ty = pos[t]

    nxt = [0] * (n + 1)
    rev = [[] for _ in range(n + 1)]

    for u in range(1, n + 1):
        ux, uy = pos[u]

        best_v = -1
        best_d1 = 10**18
        best_d2 = 10**18

        for dx, dy in dirs:
            nx, ny = ux + dx, uy + dy
            if not inside(nx, ny):
                continue
            v = grid[nx][ny]

            d1 = abs(v - t)
            d2 = abs(v - u)

            if d1 < best_d1 or (d1 == best_d1 and d2 < best_d2):
                best_d1 = d1
                best_d2 = d2
                best_v = v

        nxt[u] = best_v
        rev[best_v].append(u)

    q = deque([t])
    dist[t][t] = 0

    while q:
        v = q.popleft()
        for u in rev[v]:
            if dist[t][u] == -1:
                dist[t][u] = dist[t][v] + 1
                q.append(u)

ans_s = -1
ans_d = 10**18

for s in range(1, n + 1):
    ok = True
    worst = 0
    for t in range(1, n + 1):
        if dist[t][s] == -1:
            ok = False
            break
        worst = max(worst, dist[t][s])

    if ok and worst < ans_d:
        ans_d = worst
        ans_s = s

if ans_s == -1:
    print("impossible")
else:
    print(ans_s, ans_d)
```该实现直接反映了算法。 关键部分是下一步函数的每个目的地构造，它必须应用到目的地的距离规则和基于与当前单元格标签的接近度的平局决胜局。 之后，一切都简化为独立处理每个目的地的反向 BFS。 

一个常见的实施陷阱是忘记图表会随着每个目的地而变化。 必须在目标循环内重建下一个指针数组和反向邻接。 另一个微妙的问题是正确地分别初始化每个目的地的距离； 跨迭代共享数组会混合状态并使结果无效。 

## 工作示例

 ### 示例 1

 考虑一个小网格，其中标签已按从左到右、从上到下的递增顺序排列。 对于每个目的地，运动总是流向数字上更接近的标签，从而产生基本一致的向前运动。 来自每个目的地的 BFS 将显示许多起点可以到达所有目标，并且自助服务终端往往位于最大行驶距离最小化的中心附近。 

单一目的地的追踪$t$看起来像这样：

 | 节点| 达到$t$| 距离 |
 | ---| ---| ---|
 | t | 是的 | 0 |
 | t 的邻居 | 是的 | 1 |
 | 下一层| 是的 | 2 |

 这证实了反向 BFS 正确地从目标向外传播。 

### 示例 2

 在更不规则的网格中，假设在特定目的地的移动规则下形成一个小循环。 那么只有进入该循环的盆地内的节点才能到达目的地。 放置在该盆地之外的信息亭将无法通过有效性检查，因为来自目的地的 BFS 永远不会到达它。 

| 节点| 达到$t$| 距离 |
 | ---| ---| ---|
 | t | 是的 | 0 |
 | 盆地节点| 是的 | 有限|
 | 自行车外盆| 没有| - |

 这说明了为什么我们必须单独检查每个目的地的可达性，而不是依赖于几何连通性。

 ## 边缘情况

 关键的边缘情况是目的地引发不包括目的地本身的循环。 在这种情况下，来自目的地的 BFS 仅到达其反向盆地中的节点。 如果不重新计算每个目的地的可达性，则该盆地之外的任何自助服务终端都将错误地显示为有效。 该算法避免了这种情况，因为每个目的地都有自己的反向 BFS。 

另一个边缘情况是决胜局的模糊性。 当两个邻居距离目的地同样近时，次要规则取决于当前小区标签，而不是目的地。 混合这两种比较是错误转换的常见原因。 该实现在选择下一个单元格之前在每一步显式计算两个距离，确保确定性行为与问题定义一致。
