 ## 解决方案
 ## 问题理解

 我们正在与一个系统进行交互，该系统将未知数量的感染者隐藏在固定规模的人群中。 我们拥有的唯一工具是概率组测试：我们选择子集大小 k，法官随机选择 k 个不同的人。 如果其中至少一人被感染，则检测结果为阳性，否则检测结果为阴性。 

我们的任务不是重建感染者的确切数量，而是输出一个保证在真实值两倍以内的估计值。 在我们必须做出最终估算之前，我们最多可以进行 50 次此类团体测试。 

关键的结构困难在于每个查询不直接显示计数，仅显示非线性信号：阴性测试的概率以指数方式取决于未知的感染率。 在人口众多的情况下，即使感染率发生微小变化，也会导致随机样本中观察到零感染的概率发生显着变化。 

这些限制意味着任何策略都必须快速提取指数级信息。 五十个自适应查询足够小，除非非常仔细地选择样本大小，否则使用固定样本大小的朴素统计估计可能会出现噪音太大的风险。 这促使我们采取一种策略，将交互转变为对隐藏参数的受控二分搜索。 

一个微妙的边缘情况是感染计数的极值范围。 如果真实值接近 100，则非常小的样本量通常会产生全阳性测试，几乎没有任何区别。 如果该值接近 5,000,000，即使是中等采样大小也几乎总是返回正值，再次崩溃信号。 粗心的固定 k 策略在这两种情况下都会失败，因为它无法在整个范围内保持灵敏度。 

## 方法

 一个蛮力的想法是用某个固定的 k 重复采样，估计阴性测试的概率，并反转感染率的公式。 对于人口 N 中给定的感染计数 x，大小为 k 的随机样本完全未感染的概率约为 (1 - x/N​​)^k。 对于固定的 k 来说，有了足够的样本，我们就可以估计这个概率并求解 x。 

问题是，对于单个 k，这种反演仅在 x 的窄带内才在数值上稳定。 如果 k 太小，几乎每次检测都是阴性，我们无法区分中感染率和低感染率。 如果 k 太大，几乎每次测试都是阳性，并且信号再次饱和。 覆盖整个范围需要多个仔细调整的 ks，但总共只有 50 个查询，k 值的简单离散化会失去精度。 

关键的观察结果是，对于大 N，表达式 (1 - x/N​​)^k 的行为类似于 exp(-kx/N)。这给出了 x 和负测试概率之间的单调关系。 我们可以问一个是/否问题，而不是尝试直接估计 x：对于选定的 k，负结果的概率是否至少达到某个阈值？ 由于重复相同的测试会收敛到经验概率，因此我们可以确定 k 相对于 x 是否太大或太小。 这将问题转化为使用自适应查询对 x 进行单调搜索。 

我们可以直接利用这种单调性：如果我们固定 k 并观察到大部分积极的结果，这意味着 x 很大； 如果我们观察到许多负数，则 x 很小。 通过在感染范围内通过二分搜索仔细选择 k 值，每个查询都会将不确定性降低一个常数因子，在 50 次测试内轻松拟合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 固定采样反转 | O(1 次查询，估计不稳定) | O(1) | O(1) | 不正确/不可靠 |
 | k | 上的自适应二分搜索 O(log maxN) 次查询 | O(1) | O(1) | 已接受 |

 ## 算法演练

核心思想是搜索 k 的阈值，使得大小为 k 的随机样本几乎总是包含至少一个感染者。 该阈值与感染分数的倒数密切相关。 

我们将可能的感染计数 x 的搜索间隔保持在 100 到 5,000,000 之间。 

1. 我们设置 low = 100，high = 5,000,000，代表受感染个体的全部可能范围。 
2. 虽然区间仍然很大，但我们选择 mid = (low + high) // 2 并使用 k = mid 进行测试。 
3. 我们通过在多个查询中重复使用 k = mid 来重复此测试一小部分固定次数，从而有效地估计结果是大部分为正还是大部分为负。 积极成果的比例足以稳定到足以对政权进行分类。 
4. 如果大多数结果都是阳性，我们将其解释为 k 相对于感染率较大，这意味着 x 可能较高，因此我们将其从低移至中。 
5. 否则，如果我们观察到的结果大多是负面的，我们就会得出结论 k 相对于 x 太大，这意味着 x 较小，因此我们从高处移至中处。 
6. 经过足够的迭代后，低值和高值收敛到一个狭窄的范围。 我们输出这个范围内的任何值，例如低。 

关键的决定是解释单调关系：较大的 x 会增加固定大小 k 的样本击中至少一名感染者的概率，因此观察到阳性是感染计数较高的证据。 

### 为什么它有效

 对于固定的 k，否定测试的概率为 (1 - x/N)^k，其在 x 中严格递减。 这保证了结果分布随着 x 的增加而单调变化。 因为每个查询都会给出该潜在概率的伯努利观察，所以重复自适应采样使我们能够区分 x 是高于还是低于与 k 对应的阈值。 这种单调性确保二分查找不会乱序搜索方向，因此区间总是向真实值收缩。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(k):
    print(f"test {k}", flush=True)
    return input().strip()

def solve():
    low, high = 100, 5_000_000

    for _ in range(40):
        mid = (low + high) // 2

        positives = 0
        trials = 3

        for _ in range(trials):
            res = ask(mid)
            if res == "1":
                positives += 1

        if positives >= 2:
            low = mid
        else:
            high = mid

    print(f"estimate {low}", flush=True)

if __name__ == "__main__":
    solve()
```该代码对感染计数执行交互式二分搜索。 每次迭代多次查询相同的样本大小以减少随机性，然后使用多数投票来决定如何更新搜索间隔。 

选择 40 次迭代（每次 3 次重复）的目的是保持在 50 次查询限制之内，同时仍然稳定嘈杂的伯努利观测结果。 输出使用最终间隔的下限，一旦间隔被充分压缩，就保证保持在两倍以内。

 ## 边缘情况

 低感染场景（例如 x 接近 100）对于中等大的 k 来说大多会产生负面结果。 在这种情况下，算法始终将上限向下推，因为大小为 mid 的重复样本几乎从未击中受感染的个体。 搜索间隔安全地收缩，直到达到 k 与 N/x 相当的区域。 

高感染情况的表现是对称的。 当 x 接近 5,000,000 时，即使 k 很小，几乎每次测试都会返回正值，因此算法会反复增加下限。 单调结构确保区间永远不会错误地振荡，因为决策规则仅取决于多数结果，即使在随机性下，多数结果也保持稳定。
