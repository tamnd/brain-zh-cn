 ## 解决方案
 ## 问题理解

 我们得到了几叠硬币。 在一步操作中，两名玩家共同选择两个不同的硬币堆，并从每个硬币堆中取出一枚硬币。 他们不断这样做，直到任何地方都没有硬币为止。 任务是确定这是否可行，如果可行，则构建有效的移动序列。 

输入只是堆栈高度的列表。 每个高度告诉我们在所有移动中必须选择该堆栈多少次，因为堆栈中的每个硬币都必须恰好移除一次，并且每次选择都会从该堆栈中移除一枚硬币。 

关键的结构限制是每次移动都会消耗两个不同的堆栈。 这立即产生了全局耦合：移除的总数必须是偶数，因为每次移动都会移除两个硬币。 它还意味着与其他堆栈相比，任何堆栈都不能“太大”，因为一个堆栈只能与不同动作中的其他堆栈配对。 

约束 n ≤ 50 且总币数 ≤ 1000 意味着我们可以显式地模拟或构造操作。 执行 O(总硬币·n) 工作的解决方案很容易就足够了，甚至重复扫描的贪婪方法也可以。 

当一个堆栈支配其余堆栈时，就会出现幼稚推理的微妙失败情况。 例如，考虑输入`[5, 1, 1]`。 天真的尝试可能会尝试始终将最大的堆栈与任何其他非空堆栈配对，直到它变空。 但走两步后，小一叠已经耗尽，而大一叠还有金币，无法继续。 正确的输出是“否”，因为一个堆栈超过了所有其他堆栈的总和。 

另一种边缘情况是当总和为奇数时，例如`[1, 1, 1]`。 每一步都会使硬币总数减少 2，因此不可能达到零。 

## 方法

 蛮力视角会尝试模拟所有可能的配对序列。 每个状态都是堆栈大小的向量，每个转换都会选择两个非零堆栈。 分支因子大约为 O(n²)，深度可达硬币总数，因此即使 n = 10，搜索空间也会爆炸性远远超出可行性。 

一旦我们停止考虑序列而是考虑配对的可行性条件，问题就变得可以解决。 每个堆栈 i 都贡献 ai “存根”，这些“存根”必须与其他堆栈的存根相匹配。 我们实际上是在问是否可以在 n 个顶点上构造一个多重图，其中顶点 i 的度数为 ai，并且每条边对应于两个顶点之间的一次移动。 

这正是实现具有给定度序列的简单无向图的经典条件，除了禁止循环，因为我们不能两次选择相同的堆栈。 所以我们需要一个简单的图（没有自循环，没有多边限制实际上并不重要，因为允许在同一对之间进行多次移动，所以这是一个多图实现问题）。 

充分必要条件简化为检查度数之和是否为偶数以及最大度数是否不超过所有其他度数之和。 如果这些成立，则建设性的贪婪过程始终有效：重复连接当前最大的剩余度数。 

这与哈维尔-哈基米 (Havel-Hakimi) 的直觉相同，但这里我们明确地将边记录为移动。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力搜索 | 指数| 指数| 太慢了|
 | 贪婪配对（Havel-Hakimi 风格）| O(n² + 移动) | O(n) | 已接受 |

 ## 算法演练

 我们将剩余的硬币数量维持为类似多组的结构，反复将两个堆栈与最大的剩余数量配对。 

1. 计算所有硬币的总和。 如果是奇数，则输出“no”。 这是必要的，因为每次移动都会删除两个硬币，因此奇偶校验必须匹配。 
2. 维护当前堆栈计数及其索引的列表。 
3. 重复执行以下操作，直到所有计数变为零：

 1. 选择剩余计数最大且仍为正数的两个堆栈。 
2. 如果剩下的正数堆少于两堆，但仍剩下硬币，则输出“no”。 
3. 将两个选定的计数减 1，并将这一对记录为一次移动。 

总是选择最大的两个的原因是为了避免造成剩下的一大堆没有伙伴的情况。 如果我们延迟使用大堆栈，我们就有可能稍后将它们隔离。 
4. 输出所有记录的动作。 

构建序列后，有效性源于这样一个事实：每次移动都会将硬币总数减少恰好两个，并且永远不会尝试无效的自配对。 

### 为什么它有效

 该算法保持了不变性，即在每一步之后，剩余度数的多重集仍然可以实现为剩余顶点之间的配对序列。 选取两个最大的元素可以防止形成无法匹配的“显性残差度”。 这相当于确保在进程的每个前缀处，没有单个堆栈超过其他堆栈剩余容量的总和，这是完整配对系统中唯一的结构障碍。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if sum(a) % 2:
        print("no")
        return

    moves = []

    while True:
        # collect positive stacks
        pos = [(a[i], i) for i in range(n) if a[i] > 0]
        if not pos:
            break

        if len(pos) == 1:
            print("no")
            return

        pos.sort(reverse=True)
        (c1, i), (c2, j) = pos[0], pos[1]

        if c1 == 0 or c2 == 0:
            print("no")
            return

        a[i] -= 1
        a[j] -= 1
        moves.append((i + 1, j + 1))

    print("yes")
    for u, v in moves:
        print(u, v)

if __name__ == "__main__":
    solve()
```该实现重复重建活动堆栈列表并对其进行排序以找到两个最大的堆栈。 假设 n ≤ 50 且总操作数 ≤ 1000，每次移动的 O(n log n) 就足够了。 

最微妙的部分是当只剩下一叠正极时处理箱子。 这种情况是不可能的，因为每次移动都会消耗两个不同的堆栈。 

## 工作示例

 ### 示例 1

 输入：`n = 4, a = [1, 4, 3, 0]`我们跟踪这个过程：

 | 步骤| 剩余计数 | 已选对 | 更新计数 |
 | --- | --- | --- | --- |
 | 1 | [1,4,3,0] | (2,3) | [1,3,2,0] |
 | 2 | [1,3,2,0] | (2,3) | [1,2,1,0] |
 | 3 | [1,2,1,0] | (2,1) | [0,1,1,0] |
 | 4 | [0,1,1,0] | (2,3) | [0,0,0,0]|

 这说明了如何始终采用两个最大的堆栈来防止较小堆栈的过早耗尽，同时仍然稳定地减少占主导地位的堆栈。 

### 示例 2

 输入：`n = 3, a = [1, 1, 1]`| 步骤| 剩余计数 | 已选对 | 更新计数 |
 | --- | --- | --- | --- |
 | 1 | [1,1,1]| (1,2) | [0,0,1]|

 现在只剩下一个堆栈的计数为正，但不存在第二个堆栈。 该算法检测到这一点并返回“否”。 

这表明，即使总和是偶数，可行性也失败，因为配对在每一步都需要至少两个活动堆栈。

 ## 边缘情况

 当在所有硬币被移除之前恰好有一堆保持非零时，算法将停止并打印“no”。 用于输入`[3, 0, 0]`，第一次迭代只找到一个正堆栈，立即触发失败。 这是正确的，因为没有任何移动可以选择两个不同的堆栈，因此无法消耗剩余的硬币。 

当总和为奇数时，例如`[1, 1, 1]`，算法在模拟之前拒绝。 尽管可能会开始贪婪的配对尝试，但它最终会达到一枚剩余的硬币，并且尽早检测奇偶校验可以避免不必要的工作。 

当一个堆栈比其他堆栈大得多时，例如`[5, 1, 1, 1, 1]`，重复选择两个最大的可确保逐渐减少大堆栈，同时始终与可用的较小堆栈保持配对。 任何忽视早期最大风险的策略最终都会使其变得无与伦比，但贪婪配对通过不断耗尽风险来避免这种情况。
