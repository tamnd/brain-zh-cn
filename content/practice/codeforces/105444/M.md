 ## 解决方案
 ## 问题理解

 我们有两个自然数，但它们不是以十进制形式写的。 相反，每个数字都使用皮亚诺算术进行编码，其中数字表示为应用于零的后继函数的重复应用。 具体来说，0 写为`0`, 一个是`S(0)`, 二是`S(S(0))`， 等等。 

任务是读取两个这样的表示并计算它们的乘积，然后以相同的符号格式输出结果。 

虽然输入看起来像嵌套函数表示法，但不需要直接模拟皮亚诺乘法。 每个数字的实际值就是有多少个数字的计数`S(`包装纸出现在决赛周围`0`。 因此，每个输入字符串都会编码一个等于其嵌套深度的整数。 

输出必须再次是产品的皮亚诺表示，这意味着我们必须打印`S`应用了很多次`0`，其中计数等于两个解码整数的乘积。 

每个数字最多 1000 个字符的输入大小限制意味着解码的整数最多为 1000 个。它们的乘积最多为 1,000,000，这足够小，可以直接以输出形式构建，而无需担心溢出或性能问题。 

一个幼稚的错误是尝试对皮亚诺公理进行字面符号评估。 例如，使用定义递归扩展乘法`x · S(y) = x · y + x`重复添加会导致指数爆炸。 即使每个操作的线性递归也变得不必要的开销，因为该结构已经直接对数值进行编码。 

第二个常见的陷阱是错误解析字符串。 该结构保证格式良好，但必须仅正确计算`S`出现次数，忽略括号和零。 计数中的任何不匹配都会导致不正确的数字重建。 

边缘情况包括：

 单个`0`乘以任何值都应该产生`0`。 例如，输入`0`和`S(S(0))`必须产生`0`。 一个粗心的解析器至少假设一个`S`可能会错误输出`S(0)`。 

另一种情况是最大嵌套比如1000`S`应用程序。 如果两个输入都最大，则输出必须包含一百万`S(`包装纸。 任何没有仔细重复处理的字符串递归构造都有可能导致堆栈溢出或过多的串联开销。 

## 方法

 蛮力方法是使用其递归定义直接实现皮亚诺乘法。 首先通过重复应用来实现加法`x + S(y) = S(x + y)`，然后通过重复加法进行乘法运算`x · S(y) = x · y + x`。 这在数学上是忠实且正确的，但在操作上成本昂贵。 

如果 x 和 y 的大小均为皮亚诺形式的 n，则乘法会展开为 x 的 y 次加法，并且每次加法本身可能会遍历 x 的整个结构。 这会导致最坏情况下的复杂性约为 O(n²) 符号运算，并且由于字符串或树重建开销而导致实际情况更糟。 当输入大小高达 1000 时，这是不必要的过度杀伤。 

关键的观察结果是皮亚诺表示法是一元的。 每个数字都按字面意思编码为其值，因此解码简化为对符号进行计数。 一旦两个值都恢复为整数，乘法就变成单个算术运算。 然后通过重复对结果进行重新编码`S(`正好是产品的次数。 

这将整个问题简化为线性解析加上线性输出构造。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力皮亚诺递归 | O(n²) | O(n²) | 太慢了 |
 | 计数 + 构造 | O(n + xy) | O(n + xy) | O(xy) | 已接受 |

 ## 算法演练

 1. 读取每个输入字符串并将其解释为标记序列。 结构总是重复的形式`S(`随后是一个`0`然后右括号。 唯一有意义的信息是多少次`S(`出现在之前`0`。 该计数是数值。 
2. 扫描第一个字符串并计算与后继应用程序相对应的子字符串模式的出现次数。 每个有效数字恰好贡献一个`S`，所以计数直接给出x。 这是可行的，因为皮亚诺表示是整数的一元编码。 
3. 对第二个字符串重复同样的过程，得到y。 
4. 使用标准整数乘法计算乘积 z = x × y。 由于 x 和 y 最多为 1000，因此 z 最多为 1,000,000，这是安全的。 
5. 通过重复模式构造输出字符串`S(`正好 z 次，然后是`0`，后跟 z 右括号`)`。 
6. 输出构造好的字符串。 

### 为什么它有效

 皮亚诺表示在结构上与一元整数同构，其中后继函数的每次应用都会将值恰好增加一。 解析步骤提取该一元长度。 由于乘法是在独立于表示的自然数上定义的，因此一旦正确恢复值，就可以以标准整数形式执行算术。 重建步骤保留了正确性，因为每个后继者完全对应于原始编码中的一个结构包装器。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def parse_peano(s: str) -> int:
    # count occurrences of 'S'
    return s.count('S')

a = input().strip()
b = input().strip()

x = parse_peano(a)
y = parse_peano(b)

z = x * y

# build Peano representation
# S(S(...S(0)...))
print("S(" * z + "0" + ")" * z)
```解析函数依赖于这样一个事实：每个数字仅由重复的数字构成`S(`包装纸，所以计数`S`相当于解码整数值。 除了信任输入格式之外，不需要结构验证。 

乘法是使用本机整数完成的，考虑到较小的范围，这是有效的。 

产出建设是唯一可能重要的一步。 它创建一个大小为 O(z) 的字符串，这是不可避免的，因为输出本身就很大。 

## 工作示例

 ### 示例 1

 输入：```
S(S(0))
S(S(S(0)))
```这里第一个数字有两个`S`个应用程序，因此 x = 2。第二个应用程序有 3 个，因此 y = 3。因此 z = 6。 

| 步骤| 第一个值 x | 第二个值 y | 产品 z |
 | --- | --- | --- | --- |
 | 解析 | 2 | 3 | - |
 | 乘| - | - | 6 |
 | 构建输出 | - | - | S 重复 6 次 |

 输出：```
S(S(S(S(S(S(0)))))))
```这证实了一元乘法对应于后继层的串联。 

### 示例 2

 输入：```
S(S(S(S(S(0)))))
S(0)
```这里 x = 5 且 y = 1，因此 z = 5。 

| 步骤| x| y | z |
 | --- | --- | --- | --- |
 | 解析 | 5 | 1 | - |
 | 乘| - | - | 5 |
 | 构建输出 | - | - | 5 S 包装纸 |

 输出：```
S(S(S(S(S(0)))))
```这证明了乘以一的恒等性，直​​接保留在一元结构中。

 ## 边缘情况

 一个关键的边缘情况是当任一输入恰好是`0`。 在这种情况下，解析的值为零，因此乘积为零。 该算法产生`"S(" * 0 + "0" + ")" * 0`，它干净地折叠为`"0"`。 这避免了生成无效的结构。 

另一种情况是最大嵌套。 如果两个输入都包含 1000 个连续的`S(`应用程序中，解析结果为 x = 1000 且 y = 1000，因此 z = 1,000,000。 构建步骤产生一百万次重复`"S("`和`")"`，围绕单个`"0"`。 执行在输出大小上保持线性，并且正确性来自一元编码的直接重复语义。 

一个微妙的例子是关于计算括号而不是计算的畸形直觉`S`。 仅有的`S`很重要，因为括号是结构噪音。 即使括号发生变化，算法仍然正确，只要`S`count 与编码定义匹配。
