 ## 解决方案
 ## 问题理解

 我们得到一个非递减的整数序列，其中每个值都以十进制形式写入。 众神希望序列保持排序，这意味着每个元素必须小于或等于下一个元素。 

Eris 可以准确选择这些数字之一，并准确修改其十进制表示形式中的一位数字。 她无法插入或删除数字，只能用另一个数字替换一个数字。 生成的数字必须保持有效的十进制表示形式，这意味着它不能以前导零开头，除非整个数字变为零。 

在这个个位数的变化之后，我们检查整个序列是否仍然排序。 如果不再排序，我们输出修改后的序列。 否则，我们输出这是不可能的。 

关键限制是 n 最多为 100，而每个数字可以大到 10^15，这意味着每个数字最多有 16 位数字。 这使得总搜索空间足够小，我们可以尝试所有位置上所有可能的单位数字突变。 

一个天真的误解是认为我们必须仔细推理全局排序是如何中断的。 实际上，更改是局部的，最多影响涉及修改元素的两个相邻比较。 

当修改数字引入前导零时，会出现微妙的边缘情况。 例如，将 100 转换为 010 是无效的，即使在数字上它的表现类似于 10。另一种边缘情况是所有数字都相等。 更改数字可能仍会保留顺序，但我们特别需要打破它，而不仅仅是任意更改值。 

## 方法

 暴力策略很简单：迭代数组中的每个索引，将该数字转换为字符串，尝试用 0 到 9 之间的所有其他数字替换每个数字，重建该数字，并检查生成的完整数组是否仍然排序。 这是正确的，因为我们显式模拟了所有允许的操作。 成本来自这样的事实：对于最多 100 个数字中的每个数字，我们尝试最多 16 个数字位置，每个位置进行 9 次替换，从而产生大约 14,400 个候选值，并且对于每个数字，我们可能会在 O(n) 中检查完整数组，在最坏的情况下会进行大约 140 万次检查。 这是临界点，但在 Python 中仍然可以接受； 然而，真正的问题是大多数检查都是多余的。 

关键的观察结果是数组已经排序，因此只有修改元素的邻居可能会违反排序。 如果我们改变元素 i，那么只有 (i−1, i) 和 (i, i+1) 的比较会中断。 其他一切保持不变。 这将每次修改的验证从 O(n) 减少到 O(1)。 

因此，我们可以尝试每一个个位数的更改并在本地进行验证。 一旦我们发现破坏排序顺序的修改，我们就会输出它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | ---| ---| --- |
 | 蛮力 | O(n·d·10·n) | O(n) | 概念上太慢|
 | 最佳 | O(n·d·10) | O(n) | 已接受 |

 这里 d 是每个数字的位数，最多 16。 

## 算法演练

1. 将所有整数转换为字符串，使数字替换变得直接且受控。 这可以避免整数溢出问题并保留验证所需的数字结构。 
2. 对于数组中的每个索引 i，将其视为 Eris 应用单位数更改的唯一位置。 
3. 对于 a[i] 的字符串表示形式中的每个数字位置 j，尝试将其替换为 0 到 9 中的每个数字（不包括原始数字）。 每次替换都会产生一个候选修改数。 
4. 立即拒绝任何在多位数字中产生前导零的候选者。 唯一的例外是单字符串“0”。 
5. 构造一个临时数组，其中仅将 a[i] 替换为候选值。 
6. 检查数组是否仍然有序。 由于只有 a[i] 发生了变化，因此足以验证：

 如果 i > 0，则 a[i−1] ≤ new_value，如果 i < n−1，则 new_value ≤ a[i+1]。 
7. 如果这些条件失败，我们就成功地破坏了排序顺序，因此立即输出该数组。 
8. 如果穷尽所有选择后仍无法修改，则输出“impossible”。 

### 为什么它有效

 原始数组是已排序的，因此修改后的所有违规都必须涉及修改后的元素。 不允许对其他职位进行任何更改，未更改的职位将保留之前的所有不平等。 这将全局属性“排序数组”本地化为最多两个比较。 由于每个允许的操作都被枚举一次，因此我们找到的第一个有效违规对应于正确的解决方案（如果存在）。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_valid_change(arr, i, val):
    if i > 0 and arr[i-1] > val:
        return False
    if i + 1 < len(arr) and val > arr[i+1]:
        return False
    return True

def solve():
    n = int(input().strip())
    arr = list(map(int, input().split()))
    s = [str(x) for x in arr]

    for i in range(n):
        original = s[i]
        m = len(original)

        for j in range(m):
            for d in "0123456789":
                if d == original[j]:
                    continue

                # avoid leading zero issue
                if j == 0 and d == "0" and m > 1:
                    continue

                candidate = original[:j] + d + original[j+1:]
                val = int(candidate)

                if is_valid_change(arr, i, val):
                    new_arr = arr[:]
                    new_arr[i] = val
                    print(*new_arr)
                    return

    print("impossible")

if __name__ == "__main__":
    solve()
```该解决方案首先将每个数字转换为字符串表示形式，以便数字级操作变得直接。 嵌套循环枚举每个可能的单位数字替换。 

辅助函数`is_valid_change`捕获关键优化：它只验证修改索引的邻居，而不是重新检查整个数组。 这是将检查从线性时间减少到恒定时间的关键简化。 

我们还通过跳过多位数字中第一位数字变为“0”的任何情况来明确防止带有前导零的无效数字。 

一旦发现有效的违规配置，我们立即打印并终止，因为任何有效的答案都是可接受的。

 ## 边缘情况

 当像 1000 这样的数字的前导数字被修改时，就会出现一种边缘情况。 将其更改为 0 将创建 0000，这作为带有前导零的零的表示是无效的。 该算法明确拒绝这一点，因为它不允许前导零字符串，除非该值恰好是单字符“0”。 

另一个边缘情况是，即使值发生显着变化，修改中间元素也不会改变顺序。 例如，在 [1, 100, 1000] 中，将 100 更改为 101 仍然保留排序顺序，因此即使它是有效的数字更改，也必须拒绝它。 

最后的边缘情况是，唯一可能的中断需要增加超出其邻居的数字，但由于固定长度限制，数字替换无法实现它。 该算法详尽地检查所有数字替换，确保如果不存在违规，则正确答案是“不可能”。
