 ## 解决方案
 ## 问题理解

 我们按照歌曲的创作顺序获得了一系列歌曲。 每首歌曲都有一个标签，只能是 1、2 或 3。我们想要计算这些歌曲有多少个连续的子序列形成一个有效的“setlist”。 

有效的集合列表是从原始列表中按顺序取出的子序列，具有三个结构约束。 第一首选择的歌曲必须有标签 1，最后选择的歌曲必须有标签 3，中间的每首歌曲必须有标签 2。歌单必须至少包含三首歌曲，因此中间至少有一首 1、至少一首 3 和至少一首 2。 

这是一个对所有子数组的计数问题，但结构极其严格：每个有效的集合列表完全是通过选择包含 1 的起始位置和包含 3 的结束位置来完全确定的，并要求它们之间的所有内容都只有 2。 

n 最大为 10^6 的约束立即排除端点对的任何 O(n^2) 或 O(n^2) 枚举。 即使是 O(n log n) 的解决方案也是可以接受的，但没有必要； 该结构表明线性扫描解决方案是可能的。 

尝试所有对 (l, r) 并检查段是否有效的简单方法会重复重新计算内部检查，并在 n = 10^6 时灾难性地失败。 

如果尝试仅检查一对 1 和 3 端点而不有效地验证内部，则会出现更微妙的失败情况。 例如，在输入中

 1 2 3 1 3

 (1, 3) 是有效的，因为中间是 2，但 (1, 4) 是无效的，因为中间包含 3。忽略内部验证的简单端点配对方法会过度计数。 

## 方法

 蛮力的想法很简单：考虑每个可能的索引对 (l, r)，并检查是否可以从 l 到 r 形成有效的集合列表。 这需要验证 a[l] = 1、a[r] = 3，并且它们之间的每个元素都是 2。即使使用前缀信息优化内部检查，在最坏的情况下迭代所有对仍然需要 O(n^2)。 当 n = 10^6 时，这是完全不可行的。 

关键的观察结果是，有效段的结构强制所有内部元素为 2。这意味着有效段只能存在于最大连续 2 块内，块前紧邻 1，块后紧邻 3。 因此，我们不再考虑任意子数组，而是将问题简化为计算 1 +（一个或多个 2）+ 3 形式的模式，其中 2 在原始数组中形成一个连续区域。 

一旦我们以这种方式查看数组，我们就可以扫描一次，跟踪连续 2 的延伸，并为每个这样的延伸计算紧接在其之前出现的 1 和紧随其后出现的 3 的数量。 (1、2 块开始、2 块结束、3) 的每个选择都准确地贡献了一个有效的集合列表，并且我们可以有效地聚合这些贡献。 

这将问题转化为线性计数溢出，避免了对内部段的任何重复扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了|
 | 基于运行的计数 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们扫描数组一次，然后在概念上将其压缩为相等值的运行，但我们不需要显式存储它们。

1. 我们迭代数组，同时识别值 2 的最大连续段。每个这样的段都是有效集合列表的候选“中间区域”。 这很重要，因为任何有效的 setlist 的所有内部元素都必须等于 2，因此它不能跨越非 2 边界。 
2. 对于每个连续的 2 块，我们计算起始 1 存在多少个有效选择。这是紧邻该块左侧的连续 1 的数量，因为有效段的开始必须是按原始顺序直接位于 2 块之前的 1。 任何距离较远的 1 都会迫使段内出现非 2。 
3. 同样，我们计算结尾 3 存在多少个有效选择。这是紧邻 2 块右侧的连续 3 的数量，因为结尾 3 必须紧接在 2 块之后。 
4. 给定 2 块贡献的有效集合列表的数量是这两个计数的乘积，因为每个左选择 1 可以独立地与每个右选择 3 配对，并且所有组合都保留所需的结构。 
5. 我们在所有 2 个块上累加该乘积，对结果取模 10^9 + 7。 

### 为什么它有效

 任何有效的 setlist 都必须具有一个所有内部元素均为 2 的结构。这会强制所选段的内部完全位于数组中单个连续的 2 内。 一旦该运行被修复，端点仅由其之前出现的连续 1 数量和其之后出现的连续 3 数量来确定。 没有其他位置可以形成有效的边界，因为引入任何间隙或不匹配都会破坏内部仅出现 2 的约束。 这使得分解为每个 2 次运行的独立贡献既完整又不重叠。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # Precompute prefix counts of consecutive 1s ending at i
    left_ones = [0] * n
    if a[0] == 1:
        left_ones[0] = 1
    for i in range(1, n):
        if a[i] == 1:
            left_ones[i] = left_ones[i - 1] + 1
    
    # Precompute suffix counts of consecutive 3s starting at i
    right_threes = [0] * n
    if a[-1] == 3:
        right_threes[-1] = 1
    for i in range(n - 2, -1, -1):
        if a[i] == 3:
            right_threes[i] = right_threes[i + 1] + 1
    
    ans = 0
    
    i = 0
    while i < n:
        if a[i] != 2:
            i += 1
            continue
        
        j = i
        while j < n and a[j] == 2:
            j += 1
        
        left_count = left_ones[i - 1] if i > 0 else 0
        right_count = right_threes[j] if j < n else 0
        
        if left_count and right_count:
            ans = (ans + left_count * right_count) % MOD
        
        i = j
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先构建两个辅助数组，捕获 1 的运行在每个位置结束的时间以及 3 的运行在每个位置开始的时间。 这些允许恒定时间访问任何 2 块周围存在多少个有效的开始和结束选择。 

然后它扫描数组，跳过连续的 2 段。 对于每个这样的段，它立即向左和向右查找以确定存在多少个有效的 1-starts 和 3-ends。 将这些计数相乘即可得出该块的贡献。 

一个常见的陷阱是错误地允许不相邻的 1 或 3 参与。 使用连续运行计数可确保仅考虑边界相邻的值。 

## 工作示例

 ### 示例 1

 输入：```
1 1 1 2 2 2 3 3 3
```我们计算以每个索引结束的连续 1 和从每个索引开始的连续 3。 

唯一的 2 块是从索引 3 到 5。 

| 步骤| 2-块 (i, j) | left_count（1 秒前）| right_count（3 秒后）| 贡献 |
 | --- | --- | --- | --- | --- |
 | 1 | (3, 5) | 3 | 3 | 9 |

 2 的块被三个 1 和三个 3 包围，因此我们得到 3 × 3 = 9 个有效的集合列表。 

这证实了在前三个位置中选择起始 1 和在后三个位置中选择结束 3 的每种组合都会产生通过 2 块的有效段。 

### 示例 2

 输入：```
1 2 1 2 3 1 2 3
```我们识别两个 2 块：索引 1、索引 3 和索引 6。 

| 步骤| 2 块 | 剩余计数 | 右计数 | 贡献 |
 | --- | --- | --- | --- | --- |
 | 1 | (1, 1) | 1 | 0 | 0 |
 | 2 | (3, 3) | 1 | 1 | 1 |
 | 3 | (6, 6) | 1 | 1 | 1 |

 只有左侧至少有一个 1 和右侧至少有一个 3 正确包围的块才会起作用。 总数为2。 

这表明孤立的 2 或位置不佳的 2 除非正确括起来，否则没有任何贡献。

 ## 边缘情况

 关键的边缘情况是 2 块位于数组的边界时。 对于像这样的输入```
2 2 2 1 3 3
```任何 2 块之前都没有有效的 1，因此 left_count 为零并且不添加任何贡献。 该算法正确地忽略了该块，因为它从索引 i - 1 计算 left_count，该索引超出了范围。 

另一种情况是存在多个 2-block，但只有一些 2-block 被正确括起来：```
1 2 3 2 2 3
```第一个 2 块贡献 1 × 1，而第二个块也贡献 1 × 1。 每个都是独立处理的，因为扫描在每个非 2 边界处重置，确保不会重复计数或跨块混合。
