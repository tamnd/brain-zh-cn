 ## 解决方案
 ## 问题理解

 一座 2 × n 桥由 n 个位置构建，其中每个位置都有两个可能的图块：左侧和右侧。 在每个位置，两者中恰好有一个是安全的，并且位置 i 的安全边由长度为 n 的字符串给出，其中每个字符告诉左边或右边的图块是否正确。 

玩家按照固定顺序一一过桥。 每个玩家尝试遍历所有 n 个位置。 第一个玩家没有先验信息，并遵循确定性的“切换”行为：她首先踩在位置 1 的左侧图块上，然后在每个下一个位置交替两侧。 

后来的每个玩家都拥有部分知识。 每当前一个玩家成功踩到一块图块时，该图块就被确认为该位置的安全。 如果玩家踩到了错误的棋子，她会立即跌倒，但这次失败会揭示哪个棋子适合该位置，并且所有未来的玩家都会使用此新信息。 对于尚未确认的位置，玩家再次从最后一步开始遵循相同的切换行为。 

任务是确定有多少玩家能够成功到达位置 n，因为每次失败后都会积累知识。 

约束 n, k ≤ 1000 意味着即使是 O(nk) 模拟也很容易足够快。 每个玩家最多执行 n 步，因此简单的模拟完全符合限制。 

当早期玩家立即失败时，就会出现一种微妙的边缘情况。 例如，如果第一个位置是R，则第一个玩家总是从L开始并立即倒下，从而揭示正确的选择。 这可以级联并显着改变以后的行为。 当玩家完成整个桥时，会出现另一种边缘情况，因为没有添加新信息，并且所有后来的玩家的行为都相同，从而使答案饱和。 

## 方法

 天真的想法是从头开始独立地模拟每个玩家，总是重新计算已知的内容并在应用切换规则的同时遍历所有 n 个步骤。 每次模拟都会扫描整个字符串，每当发生不匹配时，我们都会更新全局知识并重新启动下一个玩家。 

这已经与所描述的过程相匹配，但关键的低效率在于每个玩家都在重新计算决策，即使是对于已经完全已知且稳定的桥梁部分。 不过，由于 k 和 n 最多只有 1000，即使这种重复扫描也保持在大约 10^6 次操作之内，因此不需要进行更重的优化。 

关键的观察结果是，对玩家来说唯一重要的状态是哪些位置已经被揭示。 一旦知道了位置，每个未来的玩家都会在那里做出确定的行为，并且该位置不会发生进一步的变化。 因此，我们不需要重新计算任何东西，而是简单地维护一个已知位置的布尔数组并模拟每个玩家一次。 

蛮力方法之所以有效，是因为它直接遵循规则，但在每次重新推导已知信息的方式上变得概念上多余。 优化的方法将所有历史折叠成一个单一的演化状态，并将每个玩家作为该状态的延续来运行。

 ## 算法演练

 我们维护一个已知长度为 n 的数组，指示是否已经发现了每个位置的正确板。 

我们还保留代表真实配置的给定字符串 s。 

我们一一模拟玩家。 

### 步骤

1. 初始化一个已知数组，并将所有值设置为 false，这意味着最初没有确认任何位置。 
2. 从 1 到 k 迭代每个玩家。 
3. 在每个玩家遍历开始时将变量last设置为L。 这代表玩家在前一个位置踩过的那一侧，并且由每次遍历从左步开始的规则固定。 
4. 对于从 0 到 n − 1 的每个位置 i，决定下一步行动。 
5. 如果known[i]为真，则已经确定了正确的一侧，因此玩家只需走到s[i]上并相应地最后更新。 
6. 如果known[i]为假，则玩家遵循切换规则并走到last的相反一侧。 
7. 如果所选方与 s[i] 匹配，则玩家在该位置中幸存，并且我们最后更新到所选方。 
8. 如果所选方与 s[i] 不匹配，则玩家落在位置 i 处。 我们将known[i]标记为true，因为现在显示正确的一侧是s[i]，并且我们立即停止处理该玩家。 
9. 如果玩家到达位置 n 且没有摔倒，我们就认为该玩家成功。 

### 为什么它有效

 在任何时刻，已知的位置都像固定的约束一样，迫使每个未来的玩家在那里采取相同的正确行动。 唯一的不确定性存在于未知的位置，每个玩家仅根据他们之前的一步遵循相同的确定性交替规则。 

每次失败都会严格增加已知信息的数量，并且永远不会使早期的知识失效。 这创造了一个单调的过程：已知的状态只会扩展。 由于每次扩展都是由先前未知位置的失败触发的，并且只有 n 个位置，因此过程最多在 n 个启示后稳定下来，并且后续玩家的行为相同。 因此，模拟准确地反映了游戏中信息的演变。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    known = [False] * n
    ans = 0

    for _ in range(k):
        last = 'L'
        ok = True

        for i in range(n):
            if known[i]:
                choice = s[i]
            else:
                choice = 'R' if last == 'L' else 'L'

            if choice == s[i]:
                last = choice
            else:
                known[i] = True
                ok = False
                break

        if ok:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案保持了不断发展的知识状态`known`。 每个玩家都是独立模拟的，但使用这个共享状态。 变量`last`为每个玩家重置，以强制执行每次遍历都从踩到左侧图块开始的规则。 当遇到未知位置时，算法会应用切换规则来决定移动。 不匹配会结束当前玩家并显示该位置的正确图块。 

一个常见的陷阱是错误携带`last`跨玩家。 每个玩家必须重新启动交替逻辑，否则切换模式会偏离预期规则并产生错误的转换。

 ## 边缘情况

 当第一个位置未知且与第一个玩家不匹配时，算法会立即将其标记为已知，并确保所有后来的玩家以正确的信息开始。 这是正确处理的，因为失败会在移动到下一个玩家之前触发更新。 

对于所有位置都相同的输入，第一个玩家的交替模式会导致可预测的失败序列，并最终稳定系统，之后每个剩余的玩家都确定性地成功或失败。 模拟捕捉到了这一点，因为已知只会增长而不会重置。 

当 k 相对于 n 较大时，系统在最多 n 个启示后很快达到固定状态。 在那之后，每个玩家的行为都是相同的，算法自然会计算剩余的成功玩家，而无需任何特殊的情况。
