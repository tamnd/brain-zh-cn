 ## 解决方案
 ## 问题理解

 我们正在与一串隐藏的小写英文字母进行交互，其长度可达 10,000。 我们获取信息的唯一方法是提出“给定一组字母，隐藏字符串中的哪些位置包含这些字母中的任何一个”形式的查询。 

每个此类查询都会返回一个索引列表。 重要的是，响应并没有告诉我们每个位置匹配哪个字母，只是告诉我们这些索引处的字符属于所选的集合。 

我们的目标是总共使用最多七个查询来准确地重建整个隐藏字符串，之后我们必须输出完整的字符串作为最终的答案查询。 

主要困难来自于我们无法查询每个位置的单个字母，因为在最坏的情况下每个位置需要 26 次查询。 由于仓位多达 10,000 个，任何针对每个仓位的策略都是不可能的。 总共只有七个查询的约束迫使我们从每个查询中提取全局结构。 

一种简单的方法是尝试通过查询单个字母来单独确定每个字符。 例如，问“哪些位置是‘a’？”，然后“哪些位置是‘b’？”等等。 这会立即失败，因为即使 26 个查询也已经超出了限制，而且我们仍然无法在不重复的情况下有效地映射结果。 

第二个天真的想法可能是对每个位置的字符进行二分搜索，但这需要对每个位置进行查询，这远远超出了允许的预算。 

打破许多简单实现的一个微妙的边缘情况是假设响应是对齐或分组的。 例如，如果我们查询一个像这样的集合`{a, b, c}`，我们只知道返回的位置包含这些字母之一，但我们不能假设任何顺序或分隔。 在选择不当的查询策略下，具有不同字母的两个位置可能看起来难以区分。 

驱动该解决方案的关键约束是查询总数与字母表大小相比非常小，因此每个查询必须在所有位置同时编码多位信息。 

## 方法

 暴力策略将尝试独立识别每个角色。 对于每个位置，我们将通过查询单例或子集来测试所有 26 个字母，直到分离出正确的字符。 即使这个想法的最优化版本在最坏的情况下仍然需要至少 O(26n) 字符检查，这意味着数十万次交互。 在七个查询的严格交互限制下这是不可能的。 

关键的观察是我们不需要逐个位置地识别字符位置。 相反，我们可以使用字母表上的按位编码同时识别所有字符。 

我们为每个字母分配一个 0 到 25 之间的数字，并用二进制形式表示。 由于 26 适合 5 位，因此每个字母都可以通过 5 位掩码唯一标识。 如果我们能够确定每个位置的字母代码中设置了哪些位，我们就可以重建完整的字符串。 

这可以通过使用五个精心构造的查询来实现。 在第 k 个查询中，我们询问第 k 位被设置的所有字母。 交互器返回其隐藏角色属于该子集的所有位置。 通过对所有五个位位置重复此操作，我们可以有效地并行学习每个字符的二进制表示。 

这减少了从每个位置识别到全局位提取的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个位置的暴力猜测 | O(26n) 次查询 | O(n) | 太慢了 |
 | 按位重建（最佳）| O(5n) 处理，5 个查询 | O(n) | 已接受 |

 ## 算法演练

 我们构造五个查询，每个查询对应于字母编码的一位。 

1. 为‘a’到‘z’的每个字母分配一个 0 到 25 之间的整数。将每个数字视为 5 位二进制表示形式。 
2. 对于位位置 0（最低有效位），构造一个由第 0 位为 1 的所有字母组成的查询。发送该查询并存储返回的索引列表。 
3. 对位位置 1 到 4 重复相同的过程，每次查询相应位被设置的字母集。 
4. 对于隐藏字符串中的每个位置，维护一个最初设置为 0 的 5 位整数。当某个位置出现在第 k 位的响应中时，设置该位置整数的第 k 位。 
5. 处理完所有五个查询后，将每个 5 位整数转换回其对应的字符。 
6. 使用最终答案查询输出重构的字符串。 

我们可以安全地累积每个位置的位的原因是每个查询根据其底层字符的单个二进制特征干净地分区位置。 

### 为什么它有效

 每个字符由其 5 位表示唯一确定。 每个查询同时在所有位置上精确隔离该表示的一位。 当且仅当其字符设置了该位时，一个位置才会出现在查询中。 因此，经过五次查询后，每个位置都有其字符的完整二进制签名。 由于在 0 到 25 范围内没有两个字母共享相同的 5 位模式，因此解码是明确且一致的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(chars):
    print("?", "".join(chars))
    sys.stdout.flush()
    parts = input().split()
    if not parts:
        sys.exit(0)
    n = int(parts[0])
    res = set()
    for x in parts[1:]:
        res.add(int(x))
    return res

def main():
    n = None

    # 26 letters mapped to 0..25
    alpha = [chr(ord('a') + i) for i in range(26)]
    bit_pos = [set() for _ in range(5)]

    # build queries for each bit
    for b in range(5):
        s = []
        for i in range(26):
            if (i >> b) & 1:
                s.append(alpha[i])
        bit_pos[b] = ask(s)

    # reconstruct
    code = [0] * (10**4 + 5)

    # we need n, infer from any response
    # simplest: scan max index from first query responses
    for b in range(5):
        if bit_pos[b]:
            n = max(n or 0, max(bit_pos[b]))

    if n is None:
        n = 0

    # apply bits
    for b in range(5):
        for idx in bit_pos[b]:
            code[idx] |= (1 << b)

    # decode
    ans = []
    for i in range(1, n + 1):
        ans.append(chr(ord('a') + code[i]))

    print("! " + "".join(ans))
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```实现直接反映了按位策略。 功能`ask`处理格式化和刷新，这在交互式问题中至关重要，以确保立即发送查询。 五个查询中的每一个都选择由单个二进制位确定的字母子集。 

我们将响应存储为索引集，因此成员资格检查非常有效，并且避免重复。 收集所有五个响应后，我们通过对相应位进行“或”运算来重建每个位置的字符。 最后，我们将数字代码转换回字符并输出完整的字符串。 

一个微妙的点是我们从任何响应中看到的最大索引推断字符串长度。 由于每个位置必须至少出现在一位查询中，因此这是安全的。 

## 工作示例

 考虑一个小的隐藏字符串，如“banana”。 

我们对字母子集执行五位查询。 响应可能看起来像每个位的索引集。 我们仅跟踪位置 1 到 6。 

| 位| 查询信 | 返回索引 |
 | --- | --- | --- |
 | 0 | a、c、e、g、i、k、m、o、q、s、u、w、y | 1,3,5,6 |
 | 1 | b、d、f、g、j、l、n、p、r、t、v、x、z | 2,4|
 | 2 | c、d、g、h、l、m、r、s、x、y | 3,5|
 | 3 | e、f、g、h、o、p、s、t | 1,6 |
 | 4 | i-j-k-l-m-n-o-p | i-j-k-l-m-n-o-p | 2,3,4 |

 合并每个索引的位后，每个位置都会累积一个 5 位代码，该代码可解码为正确的字母。 

该跟踪显示每个查询如何贡献部分信息以及重建如何仅在最后发生，而不是交互过程中的每个位置。 

第二个例子“aaaaa”表明重复不会造成问题。 每个位查询都会返回“a”处于活动状态的每个位的所有索引，并且重建在每个位置一致地生成“a”。

 ## 边缘情况

 关键的边缘情况是所有字符都相同。 在这种情况下，每个位查询都会返回完整的索引集，但重建仍然有效，因为所有位都一致地对齐到相同的字母代码。 该算法在查询时不依赖于区分位置，仅依赖于一致的位聚合。 

另一种情况是字母仅跨越低或高字母范围，例如仅“a”到“d”或仅“x”到“z”。 位表示仍然唯一地标识每个字符，并且未使用的位模式根本不会在任何查询中激活，这是无害的。 

最后，最大长度为 10,000 的字符串不会影响正确性，因为每个位置在重建过程中都是独立处理的，并且查询数量保持不变。
