 ## 解决方案
 ## 问题理解

 给定一个几何图，其顶点是平面地图中的交叉点，其边是路段。 道路是给定端点之间的直线段，关键的几何保证是任何两条线段仅在共享端点处相交，因此该图是图的有效平面直线嵌入。 

从这些道路中，我们必须选择形成闭环的路段子集。 从图表的角度来看，我们正在寻找一个简单的循环。 所选循环的质量是通过它包含的交叉数量来衡量的，这意味着循环上有多少个顶点。 任务是最小化这个数字，因此我们实际上需要图中最短循环的长度。 

这些限制推动了稀疏图思维。 对于多达 100000 个顶点和 300000 个边，任何尝试显式检查所有循环的方法都是不可能的。 顶点上的三次甚至二次策略是遥不可及的，甚至$O(nm)$推理太慢了。 该结构足够稀疏，邻接表上的线性或近线性遍历技术是唯一可行的方向。 

微妙的边缘情况来自根本不存在小循环的图表。 例如，具有超长弯路的树状结构可能会迫使答案很大，而假设存在三角形或小循环的简单方法将会失败。 另一个问题是，多条边可能会在多图解释中创建 2 个循环，但这里禁止平行边，因此最小可能的循环长度至少为 3。 

主要困难在于循环是全局对象，而输入是局部邻接信息。 任何正确的解决方案都必须有效地检测不重复顶点的最短闭合路径。 

## 方法

 一种直接的方法是枚举所有简单循环。 人们可以从每个顶点开始，执行 DFS，并跟踪访问的状态，同时检测我们何时返回起点。 这正确地找到了循环，但可能的 DFS 路径的数量在图的密集区域中呈指数增长。 在最坏的情况下，即使重新修剪也无法挽救它，因为图中的简单循环数量可能是指数级的。 

更结构化的改进是使用最短路径推理。 在未加权的图中，循环可以被视为占据一条边$u-v$，暂时删除它，并从中找到最短路径$u$到$v$。 添加删除的边会闭合一个循环，因此循环长度是最短路径加一。 这是正确的，因为如果删除一条边，任何循环都会成为两个相邻顶点之间的路径。 

这将问题简化为计算多对相邻顶点之间的最短路径。 从头开始为每条边运行 BFS 给出$O(m(n+m))$，对于$m = 3 \cdot 10^5$。 

关键的观察是，我们不需要独立地为每条边提供精确的最短路径。 相反，我们可以重复使用 BFS 探索，并在超过迄今为止发现的最佳循环时提前停止。 由于我们只对最小周期感兴趣，因此任何超出当前最佳答案的搜索都是无关紧要的，可以积极修剪。 

这将问题转化为具有动态截止的重复 BFS 运行。 虽然理论上仍然是最坏情况的二次，但在实践中以及在此类问题中典型的稀疏图的约束下，这种方法旨在通过。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 通过 DFS 枚举所有周期 | 指数| O(n + m) | 太慢了 |
 | 每条边最短路径的 BFS | O(m(n + m)) | O(m(n + m)) | O(n + m) | 太慢了 |
 | 带剪枝的多源 BFS | O(n(n + m)) 最差，实际上小得多 | O(n + m) | 已接受 |

 ## 算法演练

 我们依靠重复的 BFS 运行，每次运行都从一个顶点开始，并尝试发现从该起点可以形成的最短循环。 关键的技巧是，一旦 BFS 无法再改进当前的最佳答案，我们就立即停止它。 

1. 将答案初始化为一个非常大的数字。 这代表了迄今为止发现的最佳周期长度。 
2. 根据路段构建图的邻接表。 这是我们将反复遍历的结构。 
3. 对于每个顶点，运行 BFS 计算从该顶点到所有其他顶点的最短距离，但停止扩展深度已达到当前最佳答案减一的路径。 此截止值是有效的，因为通过该顶点发现的任何循环必须至少为距离加上一条边长。 
4. 在 BFS 期间，每当我们将边遍历到已访问过且不是 BFS 树中的直接父节点的顶点时，我们都会检测到循环。 循环长度是两个 BFS 深度之和加一。 如果该值较小，我们会更新全局答案。 
5. 如果在任何时候 BFS 深度超过或等于当前最佳答案，我们就会提前终止该 BFS，因为它无法提供更好的解决方案。 
6. 从所有顶点运行 BFS 后，输出找到的最佳循环长度。 

正确性取决于 BFS 从固定起点开始按长度递增顺序探索所有最短路径。 任何涉及该起始顶点的循环都将通过关闭最短路径树连接的后沿被发现。 

### 为什么它有效

 每个简单循环都可以分解为两条最短路径，在 BFS 探索期间在第一个重复顶点处相遇。 BFS 确保当我们第一次通过非树边遇到先前访问过的顶点时，发现的路径长度从源开始是最小的。 这保证了从该 BFS 根检测到的任何循环相对于该根来说都是最小的，并且对所有根取最小值捕获全局最小循环。 

修剪不会删除任何最佳解决方案，因为一旦部分路径超过已知的循环，扩展它只能产生更长的循环。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    
    coords = [tuple(map(int, input().split())) for _ in range(n)]
    
    adj = [[] for _ in range(n)]
    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        adj[a].append(b)
        adj[b].append(a)

    INF = 10**9
    ans = INF

    for start in range(n):
        if ans == 3:
            break

        dist = [-1] * n
        parent = [-1] * n
        q = deque()

        dist[start] = 0
        q.append(start)

        while q:
            v = q.popleft()

            if dist[v] >= ans - 1:
                continue

            for to in adj[v]:
                if dist[to] == -1:
                    dist[to] = dist[v] + 1
                    parent[to] = v
                    q.append(to)
                elif parent[v] != to:
                    cycle_len = dist[v] + dist[to] + 1
                    if cycle_len < ans:
                        ans = cycle_len

    print(ans if ans != INF else -1)

if __name__ == "__main__":
    solve()
```该代码根据路段构建标准邻接列表。 BFS 使用距离数组来存储距当前起始节点的最短距离和父数组，以避免将树边计为循环。 

关键的实现细节是条件`parent[v] != to`，这确保我们不会立即将 BFS 树边视为循环。 当我们找到一个不是父级的被访问邻居时，我们就找到了一个关闭循环的后沿。 

修剪条件`if dist[v] >= ans - 1`是通过避免探索无法改进迄今为止找到的最佳循环的路径来控制运行时的原因。 

## 工作示例

 ### 示例 1

 我们从存在小循环的图表开始。 不同起点的BFS会逐渐发现环，但最小的环会提前发现。 

| 开始 | BFS 的发现 | 检测到循环| 最佳答案 |
 | --- | --- | --- | --- |
 | 0 | 探索邻居，快速找到后缘 | 周期长度 4 | 4 |
 | 1 | 类似的探索| 周期长度 ≥ 4 | 4 |
 | 2 | 没有改善| 无 | 4 |

 到达紧凑循环的第一个 BFS 已经建立了最佳答案，并且剪枝可以防止来自其他顶点的不必要的完全遍历。 

### 示例 2

 该图包含多个不同大小的重叠循环。 

| 开始 | BFS 的发现 | 检测到循环| 最佳答案 |
 | --- | --- | --- | --- |
 | 0 | 首先找到一个较长的周期 | 6 | 6 |
 | 3 | 找到更小的循环 | 4 | 4 |
 | 7 | 没有改善| 无 | 4 |

 该跟踪显示了为什么需要多个 BFS 根：不同的起点暴露出不同的循环结构，并且只有全局最小值才重要。

 | 时间 | O(n(n + m)) 最坏情况，通常要少得多 | BFS 从每个节点运行，但修剪阻止了实践中的全面探索 |
 | 空间| O(n + m) | 邻接表加 BFS 数组 |

 该图是稀疏的，有$m \le 3n$，这使得 BFS 操作在实践中保持高效。 基于当前最佳循环的剪枝对于确保一旦找到小循环，搜索空间迅速崩溃至关重要。

 ## 边缘情况

 关键的边缘情况是一个几乎是一棵树的图，但包含一个额外的边缘，形成一个非常大的循环。 从大多数节点开始 BFS 将在找到后边之前探索几乎整个图，但剪枝逻辑确保一旦在其他地方发现小循环，就会尽早切断进一步的探索。 如果不存在更小的循环，该算法最终仍会发现正确的大循环。 

另一种情况是密集局部聚类，其中多个短周期重叠。 来自不同根的 BFS 确保至少一个根会尽早暴露最短周期，并且立即更新全局最小值。 

最后一个微妙的情况是最短循环不包括 BFS 的起始顶点。 即使在这种情况下，BFS 仍然会发现循环，因为循环的两个端点最终都会从一开始就到达，并且在处理第二个端点时会触发后沿条件。
