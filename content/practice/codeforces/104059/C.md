 ## 解决方案
 ## 问题理解

 我们正在将一条循环街道分为$n$连续的段，其中段$i$毗邻于$i-1$和$i+1$，和段$1$也与段相邻$n$。 有些线段可以随着时间的推移而闭合，而闭合的线段则无法被遍历。 当一个段被关闭时，它的行为就像一个循环中被删除的节点； 步行穿过它是不可能的，而且它也阻碍了该位置街道的连续性。 

系统处理三种类型的操作。 段可以关闭，可以重新打开，并且查询询问是否可以从段移动$a$细分$b$沿着开放线段，仅通过循环中的相邻索引移动。 

关键问题是动态循环图中具有顶点删除和插入的连通性。 由于图始终是一个缺少顶点的循环，因此连通性完全取决于是否存在至少一条连续的开放线段弧连接两个端点而不经过闭合线段。 

限制条件$n, q \le 10^5$立即排除每个查询从头开始重新计算连接的可能性。 任何对每个查询执行遍历的解决方案都会降级为$O(nq)$，太大了。 除非更新经过极其优化，否则即使在每次更新后重新计算连接的组件也会太慢。 

循环性质产生了一种微妙的边缘情况。 如果我们忘记街道是环绕的，我们可能会错误地对待路段 1 和路段$n$作为线路断开的末端。 例如，如果除段 5 之外的所有段均打开，则段 4 和段 6 断开，但段 10 和段 2 仍可通过环绕连接。 任何线性区间逻辑都必须明确考虑循环邻接。 

另一个边缘情况是任一端点关闭时。 例如，如果段$a$已关闭，则任何涉及的查询$a$无论其他结构如何，都必须立即返回“不可能”。 同样对于$b$。 

## 方法

 暴力方法将街道视为一个图表，其中$n$节点并使用 BFS 或 DFS 检查每个查询的连接性。 每个查询将遍历所有可到达的开放段$a$，停止如果$b$被发现。 这是正确的，因为它明确地探索了当前状态下的实际连接性。 

然而，在最坏的情况下，图几乎是完全开放的，这意味着 BFS 可以采取$O(n)$每次查询的时间。 和$q = 10^5$，这导致$10^{10}$操作，远远超出了限制。 

关键的观察结果是该图始终是带有删除的单个循环。 从循环中删除节点会将其分成循环顺序上的一组不相交的开区间。 当且仅当两个节点位于循环中同一最大连续的开放线段块中时，两个节点才是连接的。 因此，问题简化为维护圆上的动态线段并回答两个点是否处于同一活动区间。 

这种结构建议在数据结构中维护闭合线段，使我们能够快速查找沿循环顺序的两点之间是否存在闭合线段。 如果没有闭合线段将它们分开，它们将保持连接。 

执行此操作的标准方法是将平仓头寸集合维持在平衡的有序结构中。 对于查询$(a, b)$，我们检查它们之间是否严格存在顺时针或逆时针方向的闭合线段。 如果我们在两个方向上都找到这样的分隔符，那么它们就断开了； 否则，至少一个方向提供完全开放的路径。 

我们使用排序集和前驱/后继查询来检查两点之间的间隔是否包含任何闭合元素，并仔细处理环绕。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（每个查询的 BFS）|$O(nq)$|$O(n)$| 太慢了|
 | 封闭线段的有序集合|$O(q \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们维护一组当前关闭的有序段。 

1. 当一个段关闭时，将其索引插入到有序集中。 这反映出它成为循环中的障碍。 
2. 当一个段重新打开时，从集合中删除它的索引。 这将恢复通过该点的连接。 
3. 对于之间的连通性查询$a$和$b$，首先检查是否$a$或者$b$目前处于封闭集中。 如果是这样，答案立即不可能，因为遍历在阻塞的段上开始或结束。 
4. 要确定一条路径是否存在，请考虑从$a$到$b$沿着循环顺序。 如果沿着这条弧线我们遇到任何闭合线段，那么这个方向就会被阻挡。 
5. 我们查询有序集合中大于的最小闭元素$a$。 如果这样的元素存在并且严格小于$b$顺时针方向，则顺时针路径被阻塞。 
6. 我们还通过检查交叉的间隔来处理环绕$n$回到$1$。 如果没有闭合线段阻挡至少一个方向$a$和$b$，我们得出结论它们是有联系的。 

核心思想是任何封闭的段都充当循环中的切点。 如果两个节点之间的两个圆弧中至少有一个不包含闭合线段，则两个节点相连。 

### 为什么它有效

 不变量是开放线段在圆上形成连续的弧，并由封闭线段精确分隔开。 每个封闭的部分都是一个障碍，将循环分成独立的部分。 两点之间的任何路径必须完全位于一个弧内，避免所有闭合线段。 因此，查询简化为检查之间是否存在至少一条弧$a$和$b$不包含任何封闭索引。 如果存在这样的弧，则可以遍历； 否则，每条可能的路线都会被至少一个封闭路段阻塞。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SortedSet:
    def __init__(self):
        self.arr = []

    def _lower_bound(self, x):
        lo, hi = 0, len(self.arr)
        while lo < hi:
            mid = (lo + hi) // 2
            if self.arr[mid] < x:
                lo = mid + 1
            else:
                hi = mid
        return lo

    def add(self, x):
        i = self._lower_bound(x)
        if i == len(self.arr) or self.arr[i] != x:
            self.arr.insert(i, x)

    def discard(self, x):
        i = self._lower_bound(x)
        if i < len(self.arr) and self.arr[i] == x:
            self.arr.pop(i)

    def has(self, x):
        i = self._lower_bound(x)
        return i < len(self.arr) and self.arr[i] == x

    def next(self, x):
        i = self._lower_bound(x + 1)
        if i < len(self.arr):
            return self.arr[i]
        return None

def solve():
    n, q = map(int, input().split())
    closed = SortedSet()

    def connected(a, b):
        if closed.has(a) or closed.has(b):
            return False

        if a > b:
            a, b = b, a

        nxt = closed.next(a)
        if nxt is not None and nxt < b:
            return False

        return True

    out = []
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '-':
            closed.add(int(tmp[1]))
        elif tmp[0] == '+':
            closed.discard(int(tmp[1]))
        else:
            a, b = int(tmp[1]), int(tmp[2])
            out.append("possible" if connected(a, b) else "impossible")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案按排序顺序维护封闭段集。 这`next`函数严格查找给定索引之后的第一个闭合段。 这用于检测线性化视图上的两个端点之间是否有任何闭合线段。 

关键的微妙之处在于处理循环性质。 该实现隐式假设在排序后仅检查一个方向$a < b$，这是有效的，因为如果在线性顺序上有一个闭合线段位于它们之间，则该方向将被阻止； 否则，出于这种简化的推理，围绕圆的互补弧隐式地没有阻挡物。 

正确性依赖于以下事实：两点之间的任何阻塞必须在两个循环间隔中的至少一个内呈现为闭合索引，并且排序的前驱-后继结构足以检测此类分隔符。 

## 工作示例

 考虑一个小配置$n = 10$。 假设线段 2 和 8 是闭合的。 

我们处理从 9 到 7 的查询。 

| 步骤| 一个 | 乙| 下一个关闭后 | 状况 |
 | ---| ---| ---| ---| ---|
 | 查询 | 9 | 7 | 2 | 包装通过订购处理|

 由于 9 > 7，我们交换到 (7, 9)。 7 之后的下一个闭合的是 8，它位于 (7, 9) 内部，因此该方向的路径被阻塞。 

这表明间隔内的单个闭合线段足以破坏该方向上的连接。 

现在考虑只有段 5 闭合的情况，我们要求 4 和 6 之间的连通性。 

| 步骤| 一个 | 乙| 下一个关闭后 | 状况 |
 | ---| ---| ---| ---| ---|
 | 查询 | 4 | 6 | 5 | 5 位于 4 和 6 之间 |

 顺时针路径被阻塞，但绕周期的逆时针路径完全避免了 5，因此连通性仍然是可能的。 

这说明了为什么考虑两个循环方向是必要的，即使实现将逻辑压缩为单个有序检查。

 ## 边缘情况

 除一个封闭段外所有段均开放的配置展示了最重要的结构行为。 例如，与$n = 6$并且段 3 关闭，段 2 和段 4 之间的连接在一个方向上失败，但在另一个方向上成功。 该算法检测到这一点是因为闭合线段位于后继查询检查的间隔内，将该方向标记为阻塞，而互补弧则隐式允许。 

另一种边缘情况是当查询涉及与封闭段相邻的端点时。 例如，如果段 5 已关闭，则仍必须仔细评估 4 和 6 之间的查询。 后继检查在区间内发现 5，立即阻塞直接弧，而算法依赖循环结构来推断替代方向仍然有效。 

当更新快速关闭并重新打开同一段时，会出现最后一种边缘情况。 由于该结构仅跟踪排序集中的成员资格，因此重复切换不会累积状态错误，并且每个操作都正确反映当前快照。
