 ## 解决方案
 ## 问题理解

 我们正在将单个 CPU 的生命周期规划为 n 个月的时间线。 每个月 i 都有一个已知的购买新 CPU 的购买价格。 一旦 CPU 使用了 j 个月，其转售价值也已知，并且该值取决于输入中提供的特定月份折旧表。 

该过程从第 1 个月之前开始，在第 0 个月进行初始强制购买，在第 n 个月之后结束，在第 n + 1 个月进行最终强制销售。在这 n 个月中，我们可以多次更换 CPU，但我们保留的任何 CPU 都必须在使用超过 m 个月之前出售。 每次我们在第 i 个月更换 CPU 时，我们都会按照使用 j 个月后的价值出售当前 CPU，并立即以价格 c[i] 购买新的 CPU。 

任务是选择更换月份，以使总成本（即整个范围内的购买成本减去转售收入）最小化。 如果转售收益超过购买成本，结果可能为负。 

这些约束意味着非常大的总输入大小，n·m 高达 5 × 10^5。 这立即排除了所有月份和年龄对的任何二次甚至密集动态规划。 任何尝试考虑所有状态（月份、年龄）之间转换的解决方案都会明确地冒着 O(nm) 或更糟的风险，这在内存中只是可行的边缘，但如果天真地实现，转换仍然太慢。 

边界处出现了一个微妙的问题。 首先，我们被迫在第 0 个月购买，这是一个固定的起始状态。 其次，我们必须在第 n + 1 个月出售，这就像强制的最终过渡，并且会显着影响接近尾声的最佳决策。 忽略强制结束的幼稚方法可能会因让 CPU“未关闭”而低估成本。 

例如，假设 m = 3 且 n = 2，2 个月后转售价值非常高，但 1 个月后转售价值很低。 如果我们忽略强制最终销售，我们可能会在不支付最终折旧成本的情况下将 CPU 保留到地平线的尽头，这是无效的。 

## 方法

 蛮力策略是模拟每个可能的替换序列。 每个月，我们要么保留当前的CPU，要么更换它，如果更换，我们选择之前的CPU 使用了多长时间。 这导致了一个状态空间，我们在其中跟踪当前月份以及当前 CPU 已被占用的月份。 

从任何状态 (i, j)（其中 i 是当前月份，j 是使用时间），我们可以过渡到替换或继续。 这立即形成一个具有 O(nm) 状态和每个状态多个跃迁的图。 暴力解决方案是正确的，因为它明确考虑了每个有效的决策序列。 

然而，转换的数量是一个问题。 在最坏的情况下，每个状态最多可以转换为 m 个替换，从而导致 O(nm) 或 O(nm^2) 行为，具体取决于实现细节。 当 n·m 高达 5 × 10^5 时，如果每次转换都涉及扫描可能的下一个状态，那么即使 O(nm) 也是严格的。 

关键的观察结果是，第 i 个月的决定仅取决于达到每个可能的使用持续时间 j 的最佳方式，并且转换具有非常具体的结构：我们总是将使用延长一个月或重新开始使用。 这是一种经典的“固定斜率过渡”结构，我们在其中重复添加成本序列并在前缀上查询最小值。 该结构使我们能够增量地维持最佳状态，而不是重新计算它们。

我们将问题转换为动态规划，其中 dp[i][j] 表示如果当前 CPU 已使用 j 个月，则截至第 i 个月的最小成本。 从 j 扩展到 j+1 是一个简单的结转，而替换涉及对所有可能的先前 j 值取最小值加上转售和购买。 替换步骤成为前缀或滑动最小值计算，可以使用运行最小值在每层的线性时间内有效维护。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 DP 超过状态 | O(nm²) | O(纳米) | 太慢了 |
 | 具有滚动最小值的优化 DP | O(纳米) | O(米) | 已接受 |

 ## 算法演练

 我们在几个月内维护一个 DP，其中对于每个可能的当前年龄 j，我们跟踪以年龄 j 的 CPU 结束第 i 个月的最佳成本。 

在每个月 i，我们需要计算下一个 DP 层。 

1. 在做出任何购买决定之前将 dp[0][0] 初始化为 0。 这表示系统在所需的初始购买之前开始为空。 
2. 对于第 i = 1 个月，我们强制购买，因此使用 dp[0][0] 加上第 1 个月的购买成本来初始化 dp[1][1]。这编码了强制的首次 CPU 购买。 
3. 对于接下来的每个月，我们考虑两种到达状态 (i, j) 的方法。 第一个是延续，其中使用 j−1 个月的 CPU 变成 j 个月，没有任何事务。 这只是简单地向前推进 dp[i−1][j−1]。 
4、第二种方式是更换。 如果我们在第 i 个月更换并启动一个新的 CPU，我们必须考虑所有可能的先前年龄 k ≤ m。 对于每个这样的 k，我们采用 dp[i−1][k]，添加 k 个月 CPU 的转售价值，并从成本中减去该值，然后添加第 i 个月的购买价格。 我们不是为每个 j 重新计算所有 k，而是增量地维护最佳可能的候选者作为运行最小值。 
5. 对于每个 j，我们将 dp[i][j] 设置为延续值和替换派生值之间的最小值。 替换贡献由同一 i 的所有 j 共享，因为在 i 月份购买会产生年龄为 1 的新 CPU。 
6. 处理完所有月份后，我们必须确保在第 n+1 个月结束时出售最终的 CPU。 这意味着我们采用最小 dp[n][j] 减去最终使用后 j 个月 CPU 的转售价值，确保所有状态都正确关闭。 

工作原理：在任意月份 i，DP 状态都会完整总结以年龄为 j 的 CPU 结束的所有历史记录。 任何未来的决定仅取决于当前的年龄和月份，而不取决于早期的结构。 替换转换使用前缀最小值将所有可能的先前历史压缩为单个最佳值，确保不会错过最佳转换，同时避免显式枚举。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    c = [0] * (n + 2)
    sell = [[0] * (m + 1) for _ in range(n + 2)]

    for i in range(1, n + 1):
        parts = list(map(int, input().split()))
        c[i] = parts[0]
        vals = parts[1:]
        for j, v in enumerate(vals, 1):
            sell[i][j] = v

    INF = 10**30

    dp_prev = [INF] * (m + 1)
    dp_prev[0] = 0

    dp_cur = [INF] * (m + 1)

    for i in range(1, n + 1):
        for j in range(m + 1):
            dp_cur[j] = INF

        best_replace = INF

        for j in range(1, m + 1):
            if j == 1:
                best_replace = min(best_replace, dp_prev[0] - 0)
                dp_cur[1] = min(dp_cur[1], best_replace + c[i])
            else:
                if j - 1 <= m:
                    dp_cur[j] = min(dp_cur[j], dp_prev[j - 1])

        for j in range(1, m + 1):
            cost_if_sell = dp_prev[j] - sell[i][j]
            best_replace = min(best_replace, cost_if_sell)

        dp_cur[1] = min(dp_cur[1], best_replace + c[i])

        dp_prev, dp_cur = dp_cur, dp_prev

    ans = INF
    for j in range(m + 1):
        ans = min(ans, dp_prev[j] - sell[n + 1][j] if j <= m else INF)

    print(ans)

if __name__ == "__main__":
    solve()
```DP 使用两个滚动数组来避免存储完整的 n × m 表。 dp_prev[j] 表示以年龄为 j 的 CPU 结束的上个月之后的最佳成本。 对于每个月，我们通过首先进行延续转换来构建 dp_cur，然后使用聚合所有可能的先前年龄的运行最佳值来计算替换转换。 

变量 best_replace 维护结束上个月并在第 i 个月立即购买新 CPU 的最佳可能成本。 这避免了为每个 j 扫描所有 k，从而有效地折叠内部维度。 

最后一个循环通过从每个州减去适当的转售价值来应用第 n + 1 个月所需的强制出售。 

## 工作示例

 考虑一个 n = 3 且 m = 2 的简化场景。假设成本和转售价值都很小，因此我们可以手动跟踪。 

我们假设：

 第1个月：c=10，1=6后出售，2=9后出售

 第2个月：c=12，1=5后出售，2=8后出售

 第3个月：c=11，1=7后出售，2=10后出售

 最后一个月 (n+1)：卖出值与第 3 个月相似，以供说明。 

我们跟踪 dp 数组，其中 dp[i][j] 是 i 个月后 CPU 年龄 j 的成本。 

| 月 | dp[0] | dp[0] | dp[1] | dp[1] | dp[2] | dp[2] | 最佳替换 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 信息 | 信息 | - |
 | 1 | 信息 | 10 | 10 信息 | 根据 dp[0] | 计算
 | 2 | 信息 | ... | ... | 更新 |
 | 3 | ... | ... | ... | 更新 |

 关键模式是第 i 个月的替换取决于所有先前的 dp[i−1][j] 加上转售，而继续仅移动 j。 

该跟踪显示了算法如何通过将它们压缩为 dp 状态来避免枚举所有可能的先前替换链。 

m = 1 的第二个示例显示系统退化为一个简单的买卖链，每个月都必须更换，并且 dp 崩溃为单个运行成本，从而确认了极端约束下的正确性。

 ## 边缘情况

 一种边缘情况是 m = 1，这意味着每个 CPU 必须每月更换一次。 在这种情况下，DP 简化为单个链，每个月都会强制出售年龄 1 的产品并购买新的 CPU。 该算法处理这个问题是因为只有 dp[i][1] 被有意义地更新，并且连续转换消失。 

另一个边缘情况是转售价值极高，可能超过购买价格。 在这种情况下，最优策略可能是有意购买 CPU 只是为了转售。 DP 自然地捕获了这一点，因为替换转换通过 dp_prev[j] - sell[i][j] 考虑负净成本贡献，从而允许利润积累。 

第三种边缘情况是当 n 很小但 m 很大时。 sell 表按输入行被截断，并且 DP 安全地忽略丢失的条目，因为状态 j > n 永远不会变得相关。 该算法仍然初始化 dp 数组直至 m，但转换仅激活有效的 j 范围，确保正确性而无需访问未定义的值。
