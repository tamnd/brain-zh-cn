 ## 解决方案
 ## 问题理解

 我们得到了一系列排成一行的任务，其中每个任务都有一个整数难度。 一个名叫 Vanya 的角色的技能等级一开始很低，并且随着他完成任务而增加。 

Vanya 可以重复扫描序列，但他不会随机选择任务。 相反，他总是执行数组中他当前能够解决的最早的任务。 能力是通过将他当前的技能水平与任务难度进行比较来确定的。 解决任务后，他的技能会提高，这可以解锁以前太难或尚未按正确顺序完成的其他任务。 

该过程受到数组结构的限制：位置很重要，并且在任何时刻的所有可解决任务中，总是选择索引最小的任务。 一旦一项任务被接受，它就会从考虑中消失，而瓦尼亚将继续从这个位置向前寻找。 

目标是有效地模拟这个过程并确定 Vanya 将解决的任务的完整顺序。 

这些限制意味着，对于每个任务，从头开始重复扫描数组的简单模拟在最坏的情况下会导致二次行为。 当 n 达到典型的 Codeforces 限制（例如 2e5）时，O(n²) 扫描速度太慢，因为它最多需要 4e10 次操作。 这立即表明我们必须避免重复的完整遍历，而是保持对下一个有效候选者的增量访问。 

当某个时刻唯一可解决的任务远在右侧时，就会出现微妙的边缘情况，但由于技能的提高，较早的任务后来变得可以解决。 没有适当簿记的天真从左到右的贪婪扫描可能会跳过新解锁的任务，或者不必要地重新扫描，但仍然会错过排序约束。 

另一个极端情况是出现多个相同难度的任务时。 该算法必须保留最早未处理的事件，而不是在每次技能增加后从头开始扫描。 

## 方法

 一种直接的方法是从字面上模拟 Vanya 的行为。 我们重复扫描整个数组，选择最左边难度不超过当前技能的任务，将其删除，增加技能，然后重复。 这是正确的，因为它完全反映了规则。 然而，每次完整扫描的成本为 O(n)，并且我们最多可以执行 O(n) 次成功选择，从而导致总复杂度为 O(n²)。 对于大量输入，这是不可行的。 

关键的观察是，每个难度级别在位置方面的表现都是独立的：我们只关心每个难度的下一个未处理的发生。 一旦我们知道了这些位置，我们就可以在不扫描整个数组的情况下决定候选者。 

这建议为每个难度值维护一个指向其下一个未使用的事件的指针。 在当前“活跃”的所有困难（即难度≤当前技能）中，我们想要最小的下一个出现指数。 这将问题转化为在动态更新的候选者中重复提取最小值，这正是有序集或堆所支持的。 

当技能增加时，一个新的难度等级就会变得活跃，我们只需要插入它的第一个可用的出现即可。 当执行一项任务时，我们会在该难度内前进，并插入下一个任务（如果它仍然存在）。 这避免了完全重新扫描数组并将过程减少到 O(n log n)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力扫描| O(n²) | O(1) | O(1) | 太慢了|
 | 下一次出现的有序集合 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

1. 将每个难度值的所有指数按升序分组。 这让我们知道，无论遇到什么困难，下一个未使用的任务在哪里，而无需搜索。 
2. 为每个难度维护一个指针，指示其列表中第一个未使用的位置。 最初，所有指针都为零。 
3. 维护一个有序的结构，通常是一个集合，用于存储当前在 Vanya 技能下处于活动状态的所有难度的成对形式（索引、难度）。 最初，只有 ≤ 起始技能的困难才处于活动状态，因此我们插入第一次出现的困难。 
4. 反复从集合中提取最小的索引。 这代表 Vanya 将按照始终采用最早可达任务的规则解决的下一个任务。 
5. 删除索引 i 处难度为 d 的任务后，将 d 的指针前进到下一个出现的任务。 如果存在这样的情况，并且它在当前约束下有效，则将其插入到集合中。 
6. 每次成功完成任务后，都会提高Vanya的技能。 当技能增加到新值 s 时，通过将其第一次出现插入到集合中来激活此难度（前提是它存在）。 
7. 继续，直到集合变空，这意味着不再有可到达的任务。 

关键的不变量是，该集合始终准确地包含 Vanya 技能当前允许的每个难度的下一个可用候选索引。 任何有效的任务都不会被遗漏，因为每当困难变得活跃或进展时，它的下一个出现就会立即插入。 不会选择无效任务，因为只存储活动困难的索引。 

这保证了提取的最小值始终是全局顺序中正确的下一个任务，符合所需的贪婪规则。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pos = {}
    for i, v in enumerate(a):
        if v not in pos:
            pos[v] = []
        pos[v].append(i)

    # pointer per value
    ptr = {v: 0 for v in pos}

    import bisect

    # current skill starts at 1 (as implied by statement structure)
    skill = 1

    import heapq
    heap = []

    def add_value(v):
        if v not in pos:
            return
        i = ptr[v]
        if i < len(pos[v]):
            heapq.heappush(heap, (pos[v][i], v))

    # initialize active values
    for v in pos:
        if v <= skill:
            add_value(v)

    used = set()
    res = []

    while heap:
        i, v = heapq.heappop(heap)
        if (i, v) in used:
            continue
        used.add((i, v))
        res.append(i)

        ptr[v] += 1
        if ptr[v] < len(pos[v]):
            heapq.heappush(heap, (pos[v][ptr[v]], v))

        skill += 1
        if skill in pos:
            add_value(skill)

    print(*res)

if __name__ == "__main__":
    solve()
```该解决方案首先对每个难度的位置进行分组，这确保我们可以直接在事件之间跳转而无需扫描。 指针字典跟踪每个组内的进度。 

堆维护按索引排序的候选任务，这强制要求我们始终选择最左边的可用任务。 每次我们弹出一个任务时，我们都会在其难度范围内前进并推送下一个任务。 

技能进展的处理是惰性的：每当技能增加时，我们只在那一刻激活新的难度，插入它的第一次出现。 这可以避免过早地预加载所有可能性。 

一个微妙的实现细节是指针更新后可能会出现过时的堆条目。 这些是使用访问集进行过滤的，确保我们不会处理过时的（索引，值）对。

 ## 边缘情况

 当相同难度的多个任务与其他困难交织在一起时，就会出现关键边缘情况。 例如，如果难度 1 出现在位置 0、5 和 10，则算法必须确保在占据位置 0 后，下一个候选正确地前进到 5，而无需重新引入 0。 

另一个边缘情况是，当技能增加解锁一个新的难度时，该难度在数组的后缀中没有剩余的出现。 在这种情况下，不会发生插入，并且算法必须继续，而不会停止或尝试无效访问。
