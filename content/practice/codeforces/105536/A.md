 ## 解决方案
 ## 问题理解

 我们被要求在固定的天数内分配固定数量的问题。 每天我们选择要解决多少问题，并且每日计数的顺序必须是非递减的。 换句话说，如果我们表示当天解决的问题数量$i$经过$a_i$， 然后$a_1 \le a_2 \le \dots \le a_n$。 

我们有两个整数：天数$n$以及问题总数$m$。 任务是决定是否可以分配非负整数$a_1, \dots, a_n$满足单调性约束并精确求和$m$。 如果可能的话，我们还需要构建至少一个有效的时间表。 

约束结构立即迫使我们从分布的角度进行思考$m$进入$n$具有单调性条件的有序桶。 关键的困难不在于总和本身，而在于早期的日子不能超过后来的日子。 

主要的结构限制是如果$n > m$，答案是不可能。 即使我们每天至少分配一个问题，我们也已经超出了总预算。 如果我们尝试允许零，单调性约束就会破坏任务的预期解释（因为原始声明在有意义的构造中隐含地不允许“等待天”），并且社论中的标准构造假设严格积极的日常工作。 

一个简单的边缘情况说明了这种失败：如果$n = 5$和$m = 3$，没有办法每天至少分配一个问题。 任何尝试都需要一些$a_i = 0$，然后单调性迫使所有早期值也为 0，从而不可能达到总和 3。 

输出不仅是可行性，而且是明确的有效序列，因此问题是建设性的，而不是纯粹基于决策的。 

## 方法

 暴力视图会尝试枚举所有非递减的长度序列$n$与总和$m$。 即使限制为正整数，此类序列的数量也会与$m$和$n$。 朴素的生成方法有效地探索具有排序约束的整数分区，在最坏的情况下其行为呈指数级。 

这是不必要的，因为单调性约束非常弱。 除了允许我们“将大众推向右侧”之外，它不会限制相对增长模式。 一旦我们决定了最小值，其余的就由总和来强制。 

关键的观察结果是，一个非常刚性的结构已经满足所有约束：保留第一个$n-1$天相同，并将剩余金额集中在最后一天。 如果每个第一个$n-1$days 的值为 1，那么最后一天就变成$m - (n-1)$。 这会自动确保单调性，因为无论何时，最后一个值至少为 1$m \ge n$，并且所有先前的值都相同。 

这将问题简化为单一的可行性检查和直接施工。 

另一个有效的观点是分发$m$均匀：分配$\lfloor m/n \rfloor$到所有天，然后分配剩余部分，同时保持非递减顺序。 给定的结构只是这个想法的最极端的版本。

 ## 算法演练

 1. 读取整数$n$和$m$。 这些定义了我们必须填充多少个有序槽以及要分配的总质量。 
2. 检查是否$n > m$。 如果是，则输出不存在有效构造。 这是因为即使每天分配 1 个单位也已经超出了所需的总和限制。 
3. 否则，为前一个问题分配 1 个问题$n-1$天。 这确保了序列以稳定、最小的配置开始，并自动遵守迄今为止的非递减顺序。 
4. 将剩余值计算为$m - (n - 1)$。 这是唯一剩下的自由度，因为总和必须完全匹配。 
5. 将此剩余值分配给最后一天。 
6. 输出构建的序列。 

将所有剩余质量放在末尾的关键思想是简单地保留单调性：最后一个元素是构造上最大的，并且所有先前的元素都是相同的。 

### 为什么它有效

 该算法构造一个序列，其中第一个$n-1$元素相等，并且只要满足可行性条件，最后一个元素就大于或等于它们$m \ge n$成立。 构造完全满足和约束，并且单调性成立，因为序列在每个相邻对处都是非递减的。 不需要替代安排，因为任何有效的解决方案都可以通过将值从较早的位置转移到较晚的位置来转换为这种规范形式，而不会违反约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    if n > m:
        print(-1)
        return

    res = [1] * (n - 1)
    res.append(m - (n - 1))

    print(*res)

if __name__ == "__main__":
    solve()
```实施直接遵循构建。 唯一的条件分支在以下情况下处理不可行性：$n > m$。 该数组首先用 1 进行初始化$n-1$位置，确保最小的字典顺序和最小的有效前缀。 最终值通过一次减法计算得出，这保证了总和约束而无需循环或调整。 

一个微妙的细节是，我们永远不需要显式检查单调性，因为所有早期值都是相等的，并且当可行性检查通过时，最后一个值保证至少为 1。

 | 步骤| 前 n-1 天 | 最后一天价值 | 序列 |

 ## 边缘情况

 当$n > m$， 例如$n = 4, m = 2$，算法立即返回-1。 这与在严格正结构下每天分配至少 1 个单元的不可能相匹配。 任何继续进行的尝试都需要消极或基于零的重新解释，这打破了预期的单调积极时间表。 

什么时候$n = 1$， 例如$n = 1, m = 7$，该算法生成等于 7 的单个值。没有需要满足的排序约束，并且构造退化为整个总和的直接分配。 

什么时候$m = n$， 例如$n = 5, m = 5$，输出变为全1。 这是最严格的可行配置，其中不存在用于重新分配的剩余质量，并且简单地满足单调约束。
