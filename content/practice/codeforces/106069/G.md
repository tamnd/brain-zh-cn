 ## 解决方案
 ## 问题理解

 我们给出了一天，表示为从第 0 秒到第 86399 秒的时间线。沿着该时间线，有几个不相交的间隔，每个间隔代表一个计划任务。 当一项任务开始时，我们必须立即决定是执行它还是忽略它。 执行它会在整个间隔中阻碍我们并奖励一些业力。 只有当我们当前有足够的业力时才允许忽略它，并且这样做会花费该业力，同时释放整个间隔。 

在任务之外，我们希望插入尽可能多的固定长度的游戏会话。 每个会话恰好持续 M 秒，并且会话不能重叠。 

关键的交互是任务彼此不重叠，因此时间自然地分为一系列任务间隔，并且任务间隔之间有自由间隙。 然而，任务间隔是否被阻塞或变得空闲取决于我们的决定，因此实际的空闲时间线并不固定。 

输入给出 N 个任务，每个任务都有开始时间、结束时间和业力值。 我们必须针对每项任务决定是否接受它或跳过它（如果可能），然后将尽可能多的长度为 M 的游戏会话放入最终的空闲时间中。 

总 karma 总和最多为 20000 的约束是 karma 是我们需要明确跟踪的唯一真正“资源”的主要信号。 任务数量最多为 10000 个，因此任何将 karma 视为状态维度的解决方案都是合理的。 

尝试所有任务子集的简单方法是不可能的，因为这需要检查 2^N 个配置。 即使是随着时间的推移而制定的动态计划也是不够的，因为因果报应会在早期和后期的决策之间产生依赖关系。 

当需要跳过早期任务以稍后打开大的空闲块时，会出现微妙的失败情况，但跳过需要积累仅来自执行早期任务的业力。 例如，如果一项高业力任务出现得很早，我们可能会被迫去做它，即使它会降低未来的灵活性，只是为了解锁跳过后面的时间间隔。 这种依赖性使得贪婪决策变得不可靠。 

当两种不同的策略产生相同的总空闲时间但不同的段结构时，就会出现另一种边缘情况。 由于游戏需要连续的 M 长度块，因此即使总空闲时间相同，以不同方式分割空闲时间也会改变答案。 

## 方法

 强力解决方案将模拟任务决策的每个有效序列。 在每个任务中，我们都会分支为“执行”或“如果可能的话跳过”，相应地更新业力，并维护生成的阻塞间隔集。 处理完所有任务后，我们会扫描一整天并贪婪地将游戏会话打包到空闲片段中。 模拟本身是线性的，但分支会产生指数数量的状态，达到大约 2^N 种可能性，这远远超出了可行性。 

关键的观察结果是任务已经按时间排序并且不重叠，因此系统按顺序演化。 在任何时候，对未来决策唯一重要的是当前的业力以及当前有多少连续的空闲时间可以“开放”用于游戏。 

这表明对任务采用动态编程方法，其中状态跟踪业力和当前正在构建的空闲时间结构。 

主要困难在于，分数取决于空闲时间如何划分为多个部分，而不仅仅是其总长度。 这可以通过跟踪当前空闲段模 M 的剩余部分来处理。当空闲时间增加时，它可以完成一个或多个完整的游戏会话。 

因此，我们将时间线视为一系列块。 在任务之间，我们要么积累空闲时间（如果跳过），要么重置它（如果执行任务）。 每个 DP 转换都会更新业力和下一个完整游戏会话的“部分进度”。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力决定 O(2^N·N) | O(2^N·N) | O(N) | 太慢了 |
 | DP 超过任务、业力和剩余空闲时间 | O(N·K·M_state) 简化为 O(N·K) | O(N·K) | O(N·K) | 已接受 |

 这种简化来自于观察，我们不需要完整的历史，只需要业力以及已经完成了多少个完整的 M 块加上当前的剩余部分。 

## 算法演练

 我们按照时间递增的顺序处理任务。 

我们维护一个 DP 表，其中 dp[k] 存储在处理具有恰好 k 个业力的当前任务前缀后可实现的最佳结果。 每个 dp 条目存储两个值：已完成的游戏会话数和尚未形成完整 M 长度会话的当前剩余空闲时间。 

1. 将 dp[0] 初始化为具有零场比赛和零剩余空闲时间。 所有其他状态都是不可能的。 
2. 对于每个任务，我们构建一个新的 DP 数组 next_dp，最初为空。 
3.从每个可达状态（k，games，rem），我们考虑任务间隔长度L。 
4. 如果我们选择执行该任务，我们会在时间上向前移动一段阻塞间隔，因此当前的空闲段结束。 剩余的 rem 不会进一步贡献，直到我们在任务结束后积累新的空闲时间。 Karma 增加 k_i。 我们将更新后的状态存储在 next_dp[k + k_i] 中，保留游戏并将 rem 重置为 0 以供下一个空闲段开始。 
5. 如果我们选择跳过任务并且有足够的 karma，我们从 karma 中减去 k_i。 该间隔变得完全空闲，因此我们将当前空闲段延长 L 秒。 我们更新 rem + L，将完整的 M 块转换为已完成的游戏，并仅保留 rem % M 作为新的余数。 游戏数量增加 (rem + L) // M。 
6. 处理完任务的所有转换后，我们用 next_dp 替换 dp，通过保留每个业力的最大游戏数来合并状态，并在平局时存储最佳余数。 
7、完成所有任务后，我们还将最后一个任务结束到86400的最后一段时间作为最后的空闲段进行处理。 

正确性取决于以下事实：所有决策仅通过业力和当前空闲段的结构影响未来的可用性，而没有其他历史信息影响未来的选择。 

不变的是，对于每个任务前缀和每个可能的业力值，dp[k] 表示完成的游戏会话的最佳可实现数量和最佳可能的部分空闲段状态。 任何以相同 (karma, rem) 对结束的两个历史都是可以互换的，因为未来的决策仅取决于这两个值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def add_free(dp_entry, length, M):
    games, rem = dp_entry
    total = rem + length
    games += total // M
    rem = total % M
    return games, rem

def better(a, b):
    # compare (games, rem) lexicographically by games, then rem
    if a[0] != b[0]:
        return a if a[0] > b[0] else b
    return a if a[1] > b[1] else b

N, M = map(int, input().split())
tasks = []
for _ in range(N):
    l, r, k = map(int, input().split())
    tasks.append((l, r, k))

dp = {0: (0, 0)}  # karma -> (games, rem)

prev_end = 0

for l, r, k in tasks:
    length = r - l + 1
    new_dp = {}

    for karma, (games, rem) in dp.items():
        gap = l - prev_end
        base_games, base_rem = add_free((games, rem), gap, M)

        # do task
        nk = karma + k
        state = (base_games, 0)
        if nk not in new_dp:
            new_dp[nk] = state
        else:
            new_dp[nk] = better(new_dp[nk], state)

        # skip task if possible
        if karma >= k:
            nk = karma - k
            state = add_free((base_games, base_rem), length, M)
            if nk not in new_dp:
                new_dp[nk] = state
            else:
                new_dp[nk] = better(new_dp[nk], state)

    dp = new_dp
    prev_end = r + 1

# final tail
end_time = 86400
final_dp = {}

for karma, (games, rem) in dp.items():
    state = add_free((games, rem), end_time - prev_end, M)
    if karma not in final_dp:
        final_dp[karma] = state
    else:
        final_dp[karma] = better(final_dp[karma], state)

print(max(g for g, _ in final_dp.values()))
```DP 字典由当前 karma 键入，因为 karma 是控制是否允许跳过的唯一约束。 每个转换都会通过剩余机制显式更新空闲时间结构，确保部分片段稍后与额外空闲时间结合时得到正确考虑。 

一个微妙的实现细节是处理任务之间的间隙。 无论做出什么决定，该间隙始终是完全空闲的，因此在处理下一个任务之前必须将其添加到当前空闲段中。 

另一个棘手的问题是执行任务时重置剩余部分。 执行任务会破坏连续性，因此任何部分累积的空闲段都无法跨越该任务。

 ## 边缘情况

 一种重要的边缘情况是，必须执行早期任务，因为因果报应为零，即使它们很长并且会减少可用的游戏时间。 该算法可以处理这个问题，因为当 karma 不足时，永远不会生成“跳过”转换，从而迫使 DP 仅传播有效状态。 

另一种情况是，一长串的小任务创造了很多在执行和跳过之间交替的机会。 DP 在每个任务中正确地探索两个分支，确保为以后的大跳跃保留 karma 的状态不会丢失。 

第三种情况是任务之间的巨大差距主导了日程安排。 间隙处理步骤确保任务外的空闲时间始终在下一个任务决策之前累积，从而防止可能的游戏会话计数不足。
