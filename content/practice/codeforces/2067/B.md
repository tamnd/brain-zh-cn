 ## 解决方案
 ## 问题理解

 我们从一系列`n`第一个袋子里有号码，第二个袋子是空的。 由于最终的袋子必须相同，因此每个袋子最终必须包含完全相同的内容`n/2`数字。 

仅允许两个操作。 

第一个操作将数字从第一个包移动到第二个包中。 

第二个操作将第一个包中的数字加一，但前提是当前值已存在于第二个包中。 

问题是我们是否可以执行任何此类操作序列，以便最终两个袋子包含完全相同的数字多重集。 

值满足`1 ≤ a[i] ≤ n`， 和`n ≤ 1000`。 总和`n²`所有测试用例最多是`10^6`，这是一个强烈的暗示`O(n²)`解决方案是完全可以接受的。 我们不需要任何复杂的东西，例如对数数据结构或高级动态编程。 

棘手的部分是理解增量操作真正允许什么。 

假设第二个包包含该值`x`。 那么任何出现的情况`x`第一个袋子里的剩余物可能会变成`x+1`。 如果第二个袋子还包含`x+1`，该新值稍后可能会再次增加。 这意味着一个值可以通过一系列连续的值向上推，但每一步都要求当前值已经存在于第二个包中。 

一个常见的错误是只考虑频率奇偶性。 例如：```
4
1 1 2 2
```答案是`YES`。 移动一`1`和一个`2`到第二个袋子。 袋子已经一模一样了。 

但仅有奇偶校验还不够：```
4
1 1 1 4
```答案是`NO`。 

即使某些频率是偶数，也无法创建另一个频率`4`。 递增要求第二个包中存在中间值，并且没有链连接`1`到`4`。 

另一个容易犯的错误是忘记增量只会向上移动。 考虑：```
4
2 2 3 4
```答案是`NO`。 

我们可以用较小的数字创造更大的数字，但我们永远不能减少`4`到`3`或者`2`。 

了解这些限制是解决方案的关键。 

## 方法

 蛮力观点是考虑每一个可能的选择`n/2`元素被移动到第二个包中，然后模拟所有合法的增量操作。 这在原则上是正确的，因为每个有效的最终状态都对应于某些移动和增量序列。 

问题在于可能性的数量。 选择`n/2`元素出`n`已经给出了$$\binom{n}{n/2}$$可能性，即使对于中等程度的人来说也是巨大的`n`。 为了`n = 1000`，这是完全不可能的。 

为了取得进展，我们需要了解法律转型的结构。 

对数组进行排序并仅考虑每个值的频率。 

假设一个值`x`仅出现一次。 最终每个袋子中必须放入一份副本，因为最终的袋子是相同的。 由于只有一份副本，这是不可能的。 唯一的希望是在最终分割之前将该单独的副本增加到更大的值。 

现在考虑一个至少出现两次的值。 我们可以将一份放入第二个袋子中，并将另一份放入第一个袋子中。 这有效地“锁定”了价值`x`，因为有一次`x`存在于第二个包中，剩余的副本`x`可以增加到`x+1`。 

这建议从左到右处理值。 每当一个值至少出现两次时，我们就可以保留一对并将所有额外的副本推送到下一个值。 转发的副本代表可以递增的数字。 

关键的观察是奇数频率的值不能在本地固定。 必须携带一份副本。 频率为 1 的值是致命的，因为没有可用于在两个包中锚定该值的对。 

这导致了对频率的非常简单的贪婪模拟。 

让`cnt[x]`是值出现的次数`x`。 

按升序处理值。 

如果`cnt[x] == 1`，答案立即`NO`。 

否则，在形成尽可能多的值对之后`x`尽可能地，任何多余的副本都可以被推到价值`x+1`。 从操作上来说，这相当于添加$$cnt[x] - 2$$到`cnt[x+1]`每当`cnt[x] ≥ 2`。 

这与保留一对的效果完全匹配`x`并增加每个剩余的副本。 

最后，如果没有遇到频率，则构建成功。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最优贪婪频率模拟 | O(n²) | O(n) | 已接受 |

 ## 算法演练

 1. 统计每个值出现的频率。 
2. 过程值来自`1`最多`n`。 
3. 如果当前频率正好是`1`， 返回`"NO"`。 

单个副本无法在两个包之间分割，并且没有可用的对来锚定此值。 
4. 如果当前频率至少为`2`，保留一对该值。 

这两个副本代表该值在两个包中的最终出现情况。 
5. 任何剩余的副本都将转发到下一个值。 

添加`cnt[x] - 2`到`cnt[x+1]`。 

该模型增加了剩余副本`x`进入`x+1`。 
6. 继续，直到处理完所有值。 
7. 如果没有遇到频率，则返回`"YES"`。 

### 为什么它有效

 处理值时`x`，唯一的方法是使`x`出现在最后两个袋子中的是至少保留两份`x`。 每个袋子里放一份。 

如果只有一份副本，这是不可能的。 未来的操作无法创建另一个`x`，因为增量只会增加值。 

当至少存在两个副本时，保留两个副本始终是最佳选择。 任何额外的副本都无法帮助产生额外的`x`值，因此唯一有用的操作就是增加它们。 递增将它们移至频率计数中`x+1`，这正是模拟所做的。 

按升序处理值会保留所有可到达的状态。 每个多余的副本都通过连续值根据需要被推到最右边。 如果算法从未遇到频率为 1 的情况，则每个值都可以由一对锚定，并且所有多余的副本都可以向前传播。 因此存在有效的构造。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        cnt = [0] * (n + n + 5)

        for x in a:
            cnt[x] += 1

        ok = True

        for x in range(1, n + 1):
            if cnt[x] == 1:
                ok = False
                break

            if cnt[x] >= 2:
                cnt[x + 1] += cnt[x] - 2

        print("YES" if ok else "NO")

solve()
```第一部分构建频率表。 

主循环按从小到大的顺序处理值。 出现一次的频率立即证明这是不可能的，因为一份副本不可能同时出现在两个最终袋子中。 

当频率至少为二时，保留两个副本，并将每个剩余副本转移到下一个值。 这恰好对应于增加的剩余发生。 

分配的频率数组大于`n + 1`因为多余的副本可能会超出原始的最大值。 使用稍大的数组可以避免边界问题。 

一个微妙的一点是我们从来没有明确地从`cnt[x]`。 加工后值`x`，该频率再也不会被使用。 仅限剩余金额`cnt[x] - 2`很重要，所以直接将该数量添加到`cnt[x+1]`就足够了。

 ## 边缘情况

 考虑：```
2
1 2
```频率是`{1:1, 2:1}`。 该算法立即看到`cnt[1] = 1`并返回`NO`。 

这是正确的，因为一份副本`1`不能同时放入最后两个袋子中。 

考虑：```
4
1 1 1 4
```频率开始为`{1:3, 4:1}`。 

加工价值`1`转发一份剩余副本，产生频率`1`按价值`2`。 

该表变为：

 | 价值| 频率|
 | --- | --- |
 | 1 | 3 |
 | 2 | 1 |
 | 4 | 1 |

 当值`2`被处理后，算法找到频率为 1 并返回`NO`。 

这符合现实。 虽然有很多副本`1`，不存在连续的锚定价值链可以允许创造另一个`4`。 

考虑：```
8
1 1 1 1 1 1 1 4
```处理过程如下：

 | x| 碳纳米管[x] |
 | --- | --- |
 | 1 | 7 |
 | 2 | 5 |
 | 3 | 3 |
 | 4 | 2 |

 每个频率至少为 2，因此算法返回`YES`。 

剩余的副本`1`创造足够的`2`s，那些创造了足够的`3`s，这些创造了足够的`4`s。 这正是增量操作所支持的那种链。
