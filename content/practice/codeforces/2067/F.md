 ## 解决方案
 ## 问题理解

 我们得到一个整数数组和三个变量`P`,`Q`,`R`最初设置为零。 对于数组的每个元素，我们必须选择将其异或到三个变量之一。 主要限制是在每一步中，三个变量不能全部不同。 也就是说，在任何操作之后，至少有两个`P`,`Q`,`R`必须相等。 

任务是计算遵守此规则的有效操作序列的数量。 由于答案可能非常大，我们需要对结果取模$10^9 + 7$。 

约束条件很强：最多$2 \cdot 10^5$所有测试用例中的元素和数量最多$10^9$。 这立即排除了尝试所有方法的暴力解决方案$3^n$序列因为即使$3^{20}$大约是30亿。 我们需要一种利用异或结构和非独特条件的方法。 

一个微妙的点是“notpairwisedistinct”允许两个变量相等，但也允许所有三个变量相等。 这创建了特定的模式，序列可以在不违反规则的情况下传播。 对于具有重复值的数组，仅计算相同操作或仅查看最终相等性的简单方法将失败。 

例如，如果`a = [1,1,1]`，粗心的做法可能只会算数`PPP`,`QQQ`,`RRR`，但是像这样的序列`PPQ`也是有效的，因为在第二个元素之后，`P=1, Q=0, R=0`，它有两个零，因此满足规则。 

## 方法

 暴力方法在概念上很简单：为每个元素和轨道生成所有选择序列`P`,`Q`,`R`每次选择之后。 如果在任何时候它们都是不同的，则丢弃该序列。 这在原则上是正确的，但不可行，因为它的时间复杂度为$O(3^n)$。 即使是为了$n = 20$，这超出了合理的时间限制。 

关键的观察结果是，主要约束——“所有三个数字不能成对不同”——意味着在每一步，要么所有三个数字都相等，要么两个相等而第三个不同。 我们只需要跟踪几个状态，而不是所有可能的数字组合。 这使得对状态集的动态规划变得可行。 

具体来说，根据当前值的多重集定义状态`(P, Q, R)`。 我们不需要记住 P、Q、R 的确切顺序，只需记住哪些值相等即可。 如果我们将 XOR 视为可逆运算，则可以对这些状态之间的转换进行计数，而无需枚举每个序列。 更深层次的代数性质是 XOR 具有结合性和交换性，这使得我们能够将“两等一异”的状态视为一个通用类别而不是特定的数字。 

由此产生的最佳解决方案使用动态编程方法，其中少量状态在我们处理每个数组元素时向前传播计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(3^n) | O(3^n) | O(1) | O(1) | 太慢了 |
 | 多集状态上的 DP | 每个测试用例 O(n) | 每个测试用例 O(1) | 已接受 |

 ## 算法演练

 1.初始化三个变量：`all_equal = 1`表示所有三个变量都相等的序列数，`two_equal = 0`表示两个恰好相等的序列。 最初，只有国家`(0,0,0)`存在，所以`all_equal = 1`。 
2. 迭代每个元素`x`在数组中。 对于每个`x`，计算新状态：

 - 如果之前的状态是`all_equal`，我们可以异或`x`到三个变量中的任何一个。 对一个变量进行异或会破坏概率的相等性，从而导致`two_equal`。 对所有三个（或有效地没有）进行异或`all_equal`。 仔细数过之后，`all_equal_new = all_equal * 1 + two_equal * 1`和`two_equal_new = all_equal * 3 + two_equal * 2`。 
- 使用模运算来避免溢出。 
3.处理完所有元素后，答案为`all_equal + two_equal`模数$10^9 + 7$。 

关键的见解是我们永远不需要跟踪实际的数值`P, Q, R`，只有平等模式。 每个数组元素根据规则增加序列的计数，这可以在每个测试用例的线性时间内完成。 

**为什么有效：** 在每一步中，我们的状态都会捕获遵守“非成对不同”约束的所有有效序列。 对元素进行异或可以正确更新状态，因为异或是可逆的，因此不会省略任何有效序列，并且不会计算无效序列。 DP不变量是处理完i个元素后，`all_equal`和`two_equal`准确计算以该模式结尾的有效序列的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        all_equal = 1
        two_equal = 0
        
        for x in a:
            new_all_equal = (all_equal + two_equal) % MOD
            new_two_equal = (all_equal * 3 + two_equal * 2) % MOD
            all_equal, two_equal = new_all_equal, new_two_equal
        
        print((all_equal + two_equal) % MOD)

if __name__ == "__main__":
    solve()
```在解决方案中，`all_equal`和`two_equal`跟踪以这些相等模式结尾的有效序列的数量。 更新公式源自维持非不同条件的 XOR 选择的组合计数。 模运算确保我们永远不会溢出整数。
