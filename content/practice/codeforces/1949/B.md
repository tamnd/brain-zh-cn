 ## 解决方案
 ## 问题理解

 我们有两个大小的数组`n`。 

数组`a`包含开胃菜的辣度值，以及数组`b`包含主菜的辣度值。 每道开胃菜必须恰好搭配一道主菜，并且每道主菜必须恰好使用一次。 

一对`(a[i], b[j])`，这顿饭的魅力在于`|a[i] - b[j]|`。 在所有创造的美食中，我们关注的是最小的魅力。 我们的目标是选择配对，使这个最小的魅力尽可能大。 

这是一个经典的“最大化最小值”问题。 每当问题要求最大值时`X`如果某些条件是可能的，二分搜索通常是一个不错的选择。 

约束条件是关键线索。 每个测试用例都有`n ≤ 5000`，以及总和`n²`所有测试用例最多是`25 · 10⁶`。 解决方案围绕`O(n²)`每个测试用例都是可以接受的，而任何阶乘或指数都是不可能的。 枚举所有匹配项需要`n!`的可能性，甚至变得无望`n = 15`。 

一个微妙的方面是，条件涉及绝对差异。 对于固定阈值`x`，一对有效，如果`|a[i] - b[j]| ≥ x`。 

这意味着一道菜可以与小得多的东西搭配，也可以与大得多的东西搭配。 只看一方面的天真贪婪很容易失败。 

考虑：```
a = [4, 5]
b = [1, 8]
```为了`x = 3`，两个配对都有效：```
4 ↔ 1
5 ↔ 8
```和```
4 ↔ 8
5 ↔ 1
```即使存在有效匹配，始终采用最接近的有效值的贪婪也可能会阻止以后的分配。 

当许多值相等时，会出现另一个棘手的情况：```
a = [1, 1, 1]
b = [1, 1, 1]
```每一个魅力都相等`0`，所以答案是`0`。 任何假设不同值或依赖于严格不等式的算法都会在这里崩溃。 

第三种边缘情况是一个数组的所有值远低于另一个数组的所有值：```
a = [0, 0, 0]
b = [100, 100, 100]
```每一次搭配都会产生魅力`100`，所以答案是`100`。 最佳匹配并不复杂，每个配对都是等价的。 

## 方法

 蛮力的想法很简单。 生成两个数组之间所有可能的完美匹配，计算该匹配内的最小魅力，并保留最佳结果。 

这是有效的，因为它直接检查每个有效的配对安排。 问题在于匹配的数量。 有`n!`完美的搭配。 即使是为了`n = 15`，这超过了万亿种可能性。 该方法无法使用。 

目标的结构提出了不同的观点。 

假设有人告诉我们一个候选答案`x`。 不要立即询问最佳答案，而是问是/否问题：

 “我们能不能创造出完美的搭配，让每一对至少都有魅力`x`？”

 如果我们能有效地回答这个问题，那么二分搜索`x`给出最大可行值。 

剩下的挑战是可行性检查。 

对两个数组进行排序。 

对于固定阈值`x`, 一对`(a, b)`被允许时```
b ≤ a - x
```或者```
b ≥ a + x
```禁区是区间```
(a - x + 1 ... a + x - 1)
```排序后，特定值禁止的所有值`a[i]`在排序后形成一个连续的区间`b`大批。 

关键的观察是，每个有效的合作伙伴`a[i]`位于以下前缀中`b`或后缀为`b`。 

假设准确地说`k`的元素`b`从“小边”分配（`b ≤ a - x`）。 然后剩下的`n-k`元素必须来自“大的一面”（`b ≥ a + x`）。 

因为两个数组都已排序，所以我们可以检查这样的分割是否可能。 

对于第一个`k`最小的开胃菜，我们将它们与`k`最小的主菜。 我们需要```
a[i] - b[i] ≥ x
```为所有人`i < k`。 

对于其余元素，我们匹配```
a[i] with b[i-k+k] = b[i]
```按后缀之间的对齐顺序，要求```
b[i] - a[i] ≥ x
```为所有人`i ≥ k`。 

如果两个条件都适用于某个分割位置`k`，则存在有效的完美匹配。 

整个可行性测试变成了对所有可能的分裂点的扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 最佳 | 排序后每个测试用例的 O(n log V + n) | O(n) | 已接受 |

 这里`V`是取值范围，最多`10⁹`。 

## 算法演练

 ### 修复的可行性检查`x`假设两个数组都已排序。 

1. 计算数组`pref`。`pref[i]`表示是否所有位置`0..i`满足```
a[j] - b[j] ≥ x
```如果`pref[i]`是真的，那么第一个`i+1`最小的开胃菜可以与第一个搭配`i+1`最小的主菜使用“小配菜”条件。 
2. 计算数组`suff`。`suff[i]`表示是否所有位置`i..n-1`满足```
b[j] - a[j] ≥ x
```如果`suff[i]`为 true，则后缀始于`i`可以使用“大边”条件进行匹配。 
3.尝试每一个分体位置`k`从`0`到`n`。 

第一个`k`对使用小边条件。 

最后一个`n-k`对使用大边条件。 
4. 前缀部分有效，如果`k = 0`或者`pref[k-1]`是真的。 
5. 后缀部分有效，如果`k = n`或者`suff[k]`是真的。 
6. 如果这两个部分对于某些情况都有效`k`，然后阈值`x`是可以实现的。 
7. 二分查找最大可行`x`。 

### 为什么它有效

 排序后，开胃菜的每个有效伙伴要么位于已排序的左侧足够远的位置，要么位于右侧足够远的位置`b`大批。 任何满足阈值的完美匹配都会在左侧匹配的元素和右侧匹配的元素之间产生边界。 

对于固定边界`k`，当第一个中的每个对齐对时，左侧部分完全可行`k`位置至少相差`x`朝那个方向`a ≥ b + x`。 类似地，当后缀中的每个对齐对至少相差`x`朝那个方向`b ≥ a + x`。 

排序序列的重排参数保证，如果这些对齐检查失败，同一侧内的替代匹配无法修复它们。 因此，检查所有分割位置完全表征了可行性。 

因为可行性是单调的，如果有一个阈值`x`是可以实现的，那么每个更小的阈值也是可以实现的。 二分查找有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    ans = []

    for _ in range(t):
        n = int(input())
        a = sorted(map(int, input().split()))
        b = sorted(map(int, input().split()))

        def check(x):
            pref = [False] * n
            ok = True

            for i in range(n):
                ok &= (a[i] - b[i] >= x)
                pref[i] = ok

            suff = [False] * (n + 1)
            suff[n] = True

            ok = True
            for i in range(n - 1, -1, -1):
                ok &= (b[i] - a[i] >= x)
                suff[i] = ok

            for k in range(n + 1):
                left_ok = (k == 0) or pref[k - 1]
                right_ok = (k == n) or suff[k]

                if left_ok and right_ok:
                    return True

            return False

        lo, hi = 0, 10**9

        while lo < hi:
            mid = (lo + hi + 1) // 2

            if check(mid):
                lo = mid
            else:
                hi = mid - 1

        ans.append(str(lo))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```解决方案首先对两个数组进行排序。 排序至关重要，因为可行性表征依赖于元素的相对顺序。 

这`check(x)`函数验证每餐至少是否能有魅力`x`。`pref[i]`存储所有对齐对是否达到位置`i`满足`a[j] - b[j] ≥ x`。 一旦某个位置失败，每个较大的前缀也会失败，因此运行布尔值就足够了。`suff[i]`存储后缀中的每个对齐对是否满足`b[j] - a[j] ≥ x`。 

对于分割位置`k`，第一个`k`对来自左侧条件，其余来自右侧条件。 如果两个对应范围都有效，则存在完美匹配。 

二分搜索使用标准的中上模式：```
mid = (lo + hi + 1) // 2
```当只剩下两个值时，这可以避免无限循环。 

所有算术都适合 Python 整数，因为值永远不会超过`10^9`。
