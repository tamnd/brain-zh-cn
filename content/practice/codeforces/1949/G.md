 ## 解决方案
 ## 问题理解

 每栋建筑都有两条独立的信息。 

第一个字符串描述了那里举办的课程。 一栋大楼可能需要一名数学教授、一名计算机科学教授，或者根本不需要教授。 

第二个字符串描述了最初位于该位置的教授。 一栋建筑可能包含一名数学教授、一名计算机科学教授，也可能没有人。 

你驾驶的摩托车只能运载一名乘客教授。 您最多可以参观每栋建筑一次。 在参观的建筑物中，您可以先让当前与您一起乘坐的教授下车，然后再接最初位于该处的教授。 

我们的目标不是最小化任何事情。 我们只需要输出一个有效的行程，最后每个班级都有一位正确专业的教授。 

界限$n \le 2000$足够小，二次功是完全可以接受的。 挑战不是效率，而是发现隐藏的图结构，使有效的行程易于构建。 

一个常见的错误是单独考虑建筑物。 建筑物只能参观一次的限制意味着一旦我们离开建筑物，其最终的教授分配就永远固定了。 

考虑```
c = "M"
p = "M"
```该建筑已经是正确的。 参观它是没有必要的。 试图感动每一位教授的解决方案将创造出不需要存在的工作。 

另一个微妙的情况是```
c = "CM-"
p = "-CM"
```这是样本。 没有等级的建筑是交通链的起点。 如果没有这样一位教授的资源，就没有办法开始调动人们。 

关键的观察结果是，踏板车始终只运载一种教授类型，并且每次接送都会立即替换刚刚放下的教授。 这种行为自然地形成了教授类型之间的转变。 

## 方法

 暴力方法会尝试模拟所有可能的建筑物访问顺序。 即使是为了$n=20$， 有$20!$订单量已经是天文数字了。 搜索空间在达到 2000 座建筑物的实际限制之前就已经爆炸了。 

有用的观察是，仅存在三种教授类型：```
-
M
C
```对于等级类型的建筑$c_i$和初始教授类型$p_i$，想象一条有向边$$c_i \rightarrow p_i$$为什么是这个方向？ 

假设我们带着一位这样的教授到达$c_i$。 我们可以把那位教授扔到大楼里，让他的班级满意。 然后我们拿起原来的教授类型$p_i$并继续携带该类型。 

所以参观这座建筑改变了携带类型$c_i$进入$p_i$。 

现在，每个建筑物都成为图中只有三个顶点的有向边：```
-, M, C
```有效行程对应于遍历边，使得一个建筑物的输出类型等于下一建筑物所需的输入类型。 这正是欧拉遍历的定义。 

因为该语句保证存在有效的行程，所以生成的图是欧拉图。 我们只需要找到一个欧拉电路，然后将其边缘转换回滑板车操作。 

由于该图只有三个顶点，Hierholzer 的算法就足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决|
 | --- | --- | --- | --- |
 | 蛮力 |$O(n!)$|$O(n)$| 太慢了|
 | 欧拉旅游建设|$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 ### 1. 构建图表

 创建对应于的三个顶点：```
0 = -
1 = M
2 = C
```对于每栋建筑$i$，添加有向边$$c_i \rightarrow p_i$$并将建筑物索引存储在该边缘上。 

### 2. 求欧拉回路

 从顶点开始运行 Hierholzer 算法`-`。 

每条边必须仅使用一次。 

Hierholzer 生成边的顺序就是建筑物参与运输链的顺序。 

### 3. 将欧拉电路转换为建筑物

 让欧拉电路返回一个边序列$$e_1, e_2, \dots, e_k$$其中每条边对应于一座建筑物。 

连续边满足$$p(e_i)=c(e_{i+1})$$这正是滑板车所需要的兼容性条件。 

### 4.生成命令

 开车前往第一边的建筑。 

如果它的最初教授不是`-`， 问题`PICKUP`。 

对于每个后续建筑物：

 1.`DRIVE`到那栋大楼。 
2. 如果我们有一位教授，问题`DROPOFF`。 
3. 如果建筑物最初有一位教授，则发出`PICKUP`。 

处理完最后一座建筑后，如果仍有教授被携带，则发出最终的`DROPOFF`。 

欧拉循环保证了每位下车教授都拥有该大楼的正确专业知识。 

### 为什么它有效

 每条边代表一座建筑物，它将携带的教授类型从其班级类型转换为其原始教授类型。 

在欧拉电路中，每条边的结束顶点等于下一条边的起始顶点。 因此，在一栋大楼中选择的教授类型正是下一栋大楼所需的类型。 

当我们把一位教授送到一栋大楼时，该教授的专业化与该大楼的班级类型相匹配，因为边缘从该班级类型开始。 然后拾取器将携带类型更改为边的目标顶点。 

由于每条边都只使用一次，因此每个建筑物都只处理一次。 由于遍历是欧拉的，因此所有类型要求在整个链中都匹配。 每节课都会有一位具有正确专业方向的教授结束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = input().strip()
    p = input().strip()

    mp = {'-': 0, 'M': 1, 'C': 2}
    rev = ['-', 'M', 'C']

    g = [[] for _ in range(3)]

    for i in range(n):
        u = mp[c[i]]
        v = mp[p[i]]
        g[u].append((v, i + 1))

    ptr = [0] * 3
    stack_v = [0]
    stack_e = []
    euler = []

    while stack_v:
        v = stack_v[-1]

        if ptr[v] < len(g[v]):
            to, idx = g[v][ptr[v]]
            ptr[v] += 1

            stack_v.append(to)
            stack_e.append(idx)
        else:
            stack_v.pop()
            if stack_e:
                euler.append(stack_e.pop())

    euler.reverse()

    ops = []

    if not euler:
        print(0)
        return

    first = euler[0]
    ops.append(f"DRIVE {first}")

    carrying = False

    if p[first - 1] != '-':
        ops.append("PICKUP")
        carrying = True

    for b in euler[1:]:
        ops.append(f"DRIVE {b}")

        if carrying:
            ops.append("DROPOFF")
            carrying = False

        if p[b - 1] != '-':
            ops.append("PICKUP")
            carrying = True

    if carrying:
        ops.append("DROPOFF")

    print(len(ops))
    print("\n".join(ops))

solve()
```该图仅包含三个顶点，但最多包含 2000 条边。 每条边都存储建筑物索引，因为最终行程必须引用建筑物，而不是图形边。 

Hierholzer 算法是迭代实现的。 这`stack_v`stack存储当前DFS路径上的顶点，而`stack_e`存储相应的边缘标识符。 当顶点用完出边时，最新的边将成为欧拉电路的一部分。 

将生成的边列表反转后，我们就得到了遍历顺序。 

命令生成阶段直接反映边缘的解释。 拾取将携带的教授类型更改为边缘目的地。 下降消耗了从前一个边缘携带的教授。 Euler 属性保证每个下车专业化都符合下一栋建筑的等级要求。 

最微妙的细节是顺序`DROPOFF`然后`PICKUP`。 该声明明确允许在建筑物内最多按顺序接送一次。 逆转它们将违反规则。

 ## 边缘情况

 考虑```
1
M
M
```该建筑已经包含了正确的教授。 用图形术语来说，这是一个自循环`M → M`。 Hierholzer 自然地处理自循环。 参观这座建筑只是简单地放弃并选择相同的专业化，从而保持正确性。 

考虑```
3
CM-
-CM
```教授的唯一来源是没有班级的大楼。 它的边是`- → M`，这成为欧拉电路的自然开始。 算法从那里开始，选择数学教授，并通过链传播专业知识。 

考虑```
4
MMCC
MMCC
```每条边都是一个自循环。 实际上没有教授需要搬家。 欧拉遍历仍然存在并且仍然有效，因为每个建筑物已经满足其类别要求。 生成的行程遵循单次访问限制，并且绝不会创建不兼容的分配。 

所有这些情况下的关键不变量都没有改变：当建筑物边缘`c → p`正在处理，教授掉在那里有专业`c`，而忘乎所以的教授有专业`p`。 欧拉遍历保证这些类型在连续建筑物之间匹配。
