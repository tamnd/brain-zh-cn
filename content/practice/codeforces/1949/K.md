 ## 解决方案
 ## 问题理解

 我们给出了正整数的多重集和三个所需的组大小。 每个数字必须恰好属于三个组之一，并且每个组必须恰好包含所请求的元素数量。 

分割数字后，我们只看三组的总和。 如果这些金额是$s_a$,$s_b$， 和$s_c$，它们必须形成一个非退化三角形。 由于所有值都是正数，因此三角形条件简化为一个不等式：$$\max(s_a,s_b,s_c) < s_a+s_b+s_c-\max(s_a,s_b,s_c)$$换句话说，任何边都不能至少是总周长的一半。 

所有测试用例的元素总数最多为$200\,000$。 这立即排除了任何指数、任何 DP 子集，甚至$O(n^2)$每个测试用例。 我们需要一些接近的东西$O(n \log n)$，这强烈建议排序加上贪心构造。 

棘手的部分是组大小是固定的。 一旦组满了，我们就不能随意移动元素。 

一个容易犯的错误是认为只有最大的元素才重要。 

考虑：```
n = 6
sizes = (2,2,2)
values = [3,1,1,1,1,1]
```总和是$8$，所以每个组的总和必须严格小于$4$。 最大的元素只有$3$，看起来无害。 

但每个组必须包含两个数字。 唯一可能包含的组$3$有总和$4$，其余组有总和$2$和$2$。 得到的边是$(4,2,2)$，这是退化的。 正确答案是`NO`。 

另一个危险的情况是存在解决方案但不能简单地将最大的数字打包在一起。```
sizes = (1,2,2)
values = [2,2,2,1,1]
```将两个最大的数字放入同一组得出总和$(2,4,2)$，失败了。 

有效的分区是：```
2
2 1
2 1
```有总和$(2,3,3)$。 

该算法必须推理未来的放置，而不仅仅是当前的总和。 

## 方法

 暴力解决方案将尝试所有方法选择第一组，然后尝试所有方法选择第二组，并将剩余的数字放入第三组。 

例如，如果尺寸是$n_a,n_b,n_c$，分区数为$$\binom{n}{n_a}\binom{n-n_a}{n_b}.$$即使是为了$n=40$，这已经是一个天文数字了。 和$n$最多$200\,000$，暴力破解是完全不可能的。 

关键的观察结果是三角形有效性仅取决于最终组的总和。 

让$$T = \sum x_i.$$三角形条件相当于要求每组和严格小于$T/2$。 

现在想象一下从最大到最小处理数字。 

假设一组当前有总和$S$并且仍然需要$k$更多元素。 即使在最乐观的情况下，这些未来要素也必须至少贡献$k$剩余的最小数。 

这给出了最终组总和的下限。 

如果下限已经达到$T/2$，这个组永远不会变得有效。 

这将问题转化为贪婪的可行性检查。 在分配最大的剩余数字时，我们只将其放入一个组中，该组的最佳可能未来仍使最终总和低于$T/2$。 

由于只有三个组，因此在排序后检查每个元素的所有候选组是一项持续的工作。 

| 方法| 时间复杂度| 空间复杂度| 判决|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 最优贪心构造 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 计算总和$T$。 
2. 将所有数字按升序排序。 
3. 预先计算排序数组的前缀和。 

前缀和可以让我们快速获得最小的和$k$数字。 
4. 对于每个组，存储：

 - 当前的总和，
 - 还有多少个插槽是空的，
 - 分配给它的实际编号。 
5. 从最大到最小处理数字。 
6. 令当前数字为$x$。 
7. 尝试三组中的每一组。 

假设一组当前有总和$S$并且仍然需要$r$元素包括$x$。 

放置后$x$，该组仍需要$r-1$更多元素。 

最小可能的额外贡献是最小的总和$r-1$所有尚未处理的号码中的号码。 

由于我们从最大到最小进行处理，因此未来的数字恰好是较小的值。 使用全局最小的$r-1$值给出了始终安全的下限。 
8. 定义$$\text{best\_possible} = S + x + \text{sumSmallest}(r-1).$$如果$$2 \cdot \text{best\_possible} < T,$$那么即使在最乐观的完成情况下，该组也可以保持有效的三角形边。 

1. 地点$x$进入满足该条件的第一组。 
2. 如果没有团体可以接受$x$， 输出`NO`。 
3. 如果所有号码都分配成功，则输出`YES`和三组。 

### 为什么它有效

 不变量是：

 对于每个组，至少还有一种方法来完成剩余的位置，同时将其最终总和严格限制在以下范围内$T/2$。 

当我们输入号码时$x$，我们只允许保留这个不变量的赋值。 

数量$$S + x + \text{sumSmallest}(r-1)$$是该小组在接受后可以达到的最小最终总和$x$。 如果即使这个最小值已经至少$T/2$，然后放置$x$那里使成功成为不可能。 

相反，如果不平等成立，该群体仍有空间保持在以下水平$T/2$。 

从最大到最小处理数字至关重要。 大数字是最难放置的。 如果在不违反不变性的情况下，一个大数无法放入任何组，那么后来的较小数就无法修复这种情况。 

当算法完成时，每个组仍然满足剩余槽位为零的不变量。 下界成为精确的最终总和，因此每个组的总和严格低于$T/2$。 这正是三角形条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n, na, nb, nc = map(int, input().split())
        a = list(map(int, input().split()))

        total = sum(a)

        a.sort()

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]

        groups = [[], [], []]
        sums = [0, 0, 0]
        rem = [na, nb, nc]

        ok = True

        for i in range(n - 1, -1, -1):
            x = a[i]

            placed = False

            for g in range(3):
                if rem[g] == 0:
                    continue

                need_after = rem[g] - 1

                min_final_sum = sums[g] + x + pref[need_after]

                if 2 * min_final_sum < total:
                    groups[g].append(x)
                    sums[g] += x
                    rem[g] -= 1
                    placed = True
                    break

            if not placed:
                ok = False
                break

        if not ok:
            out.append("NO")
            continue

        out.append("YES")
        out.append(" ".join(map(str, groups[0])))
        out.append(" ".join(map(str, groups[1])))
        out.append(" ".join(map(str, groups[2])))

    sys.stdout.write("\n".join(out))

solve()
```第一步是对值进行排序。 未来的每一次可行性检查都取决于了解哪些数字仍然小于当前数字。 

前缀和数组是使贪婪检查快速的实现细节。 而不是重复求和最小的$k$值，我们得到该数量$O(1)$。 

表达式```
min_final_sum = sums[g] + x + pref[need_after]
```是算法的核心。 它代表了如果我们放置的话，该组可能拥有的最小最终总和$x$现在就投入其中。 

严格的不平等```
2 * min_final_sum < total
```必须保持严格。 替换为`<=`将允许退化三角形，其中一侧等于其他两条的总和。 

另一个微妙之处是我们将实际值直接存储在组中。 该声明要求提供数字，而不是指数。

 ## 边缘情况

 考虑：```
6 2 2 2
1 1 1 1 1 3
```总和是$8$。 任何包含以下内容的组$3$还必须包含一个以上的元素，因为每个组的大小都是$2$。 它的最小可能的最终总和是$4$。 

该算法计算：```
min_final_sum = 3 + 1 = 4
```并检查：```
2 * 4 < 8
```这失败了。 

任何团体都不能接受$3$，所以答案是正确的`NO`。 

现在考虑：```
5 1 2 2
2 2 2 1 1
```总和是$8$。 

第一个$2$可以进入尺寸-$1$组，因为它的最终总和仍然存在$2$，安全地在下面$4$。 

剩下的两个$2$值不能合并到同一组中，因为这将迫使未来的总和$4$。 可行性检查拒绝该放置并将其分配到不同的组中。 

最终总和变为：```
2, 3, 3
```满足三角不等式。 

这正是仅基于当前总和的朴素贪婪失败，而基于可行性的贪婪成功的情况。 

该解决方案依赖于通过未来可能的最小贡献来展望未来，这就是它正确处理这些边界情况的原因。
