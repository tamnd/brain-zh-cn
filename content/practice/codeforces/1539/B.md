 ## 解决方案
 ## 问题理解

 我们得到一个代表歌曲的小写字符串以及对该字符串的连续子字符串的许多查询。 

每个字母贡献的值等于其在字母表中的位置。 例如，`a = 1`,`b = 2`,`c = 3`， 等等。 对于查询`[l, r]`，我们从位置查看子串`l`定位`r`。 每个字符重复的次数与其字母值相同，我们需要得到的扩展字符串的长度。 

我们可以考虑每个字符对最终长度的贡献有多大，而不是实际构建扩展的字符串。 如果一个字符是`c`，它贡献`3`。 如果一个字符是`z`，它贡献`26`。 子字符串的答案只是该范围内所有字符的这些值的总和。 

约束是问题的关键部分。 字符串长度和查询次数都可以达到`100000`。 扫描每个查询的整个子字符串的解决方案最多需要`100000 × 100000 = 10^10`最坏情况下的操作，远远超出了两秒内可以运行的范围。 我们需要一种方法在经过一些预处理后以恒定或对数的时间回答每个查询。 

一个容易犯的错误是将这项任务解释为计算不同的字母。 考虑：```
s = "aaa"
query = [1, 3]
```每个`a`贡献`1`，所以答案是：```
1 + 1 + 1 = 3
```正确的输出是`3`， 不是`1`。 

另一个常见错误是使用从零开始的查询索引，即使输入使用从一开始的位置。 

例子：```
s = "ab"
query = [1, 1]
```子串是`"a"`，所以答案是`1`。 

如果我们不小心将查询视为从零开始，我们将访问错误的字符并产生错误的结果。 

当查询覆盖整个字符串时，会出现第三种微妙的情况：```
s = "zzz"
query = [1, 3]
```答案是：```
26 + 26 + 26 = 78
```前缀和边界中的任何差一错误都会立即在此类范围上产生错误的结果。 

## 方法

 最直接的解决方案是独立处理每个查询。 对于查询`[l, r]`，我们迭代该子字符串中的所有字符，将每个字母转换为其字母表位置，对值求和，然后打印结果。 

这种方法是正确的，因为所需的答案正是该总和。 问题是效率。 一个子串最多可以包含`100000`字符，并且可以有`100000`查询。 在最坏的情况下，我们会执行大约`10^10`角色访问，这太慢了。 

问题的结构提出了更好的方法。 每个查询都要求同一数组的连续段上的值之和。 一旦我们将每个字符转换为其字母值，该任务就变成了一个经典的范围和查询问题。 

对于静态数组上的范围和查询，前缀和是标准工具。 如果`pref[i]`存储第一个的总价值`i`字符，然后是任意区间的总和`[l, r]`可以通过减去两个前缀和得到：```
pref[r] - pref[l - 1]
```预处理需要线性时间，并且每个查询都变成常数时间计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nq) | O(1) | O(1) | 太慢了|
 | 最佳 | O(n + q) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读`n`,`q`，和字符串`s`。 
2. 创建前缀和数组`pref`长度`n + 1`， 和`pref[0] = 0`。 
3. 从左到右遍历字符串。 
4. 对于每个字符，使用以下方法计算其字母位置：```
ord(character) - ord('a') + 1
```5. 将累积和存储在前缀数组中。`pref[i]`应包含第一个的总价值`i`人物。 
6. 对于每个查询`[l, r]`，计算：```
answer = pref[r] - pref[l - 1]
```7. 输出答案。 

### 为什么它有效

 前缀数组保持不变式`pref[i]`等于位置中字符值的总和`1`通过`i`。 

当我们计算时`pref[r] - pref[l - 1]`,职位贡献`1`通过`l - 1`出现在两个术语中并相互抵消。 剩下的就是位置值的总和`l`通过位置`r`，这是扩展字符串所需的长度。 由于每个字符对最终长度都有独立的贡献，因此这个总和正是答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    s = input().strip()

    pref = [0] * (n + 1)

    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + (ord(s[i - 1]) - ord('a') + 1)

    ans = []

    for _ in range(q):
        l, r = map(int, input().split())
        ans.append(str(pref[r] - pref[l - 1]))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```第一部分读取输入并将字符串转换为累积字母值总和。 表达式`ord(s[i - 1]) - ord('a') + 1`地图`a`到`1`,`b`到`2`， 等等。 

前缀数组使用基于 1 的索引。 此选择与查询格式相匹配，并使范围公式变得简单。 值在`pref[0]`为零，这允许从位置开始查询`1`如无特殊情况，按规定处理。 

对于每个查询，通过一次减法即可获得答案。 不会再次扫描子字符串中的字符。 

一个常见的实现错误是混合字符串索引和前缀索引。 字符串本身是从零开始的，所以字符`i`在前缀结构中对应于`s[i - 1]`。

 ## 边缘情况

 考虑尽可能最小的输入：```
1 1
a
1 1
```前缀数组变为：```
pref = [0, 1]
```答案是：```
pref[1] - pref[0] = 1
```该算法正确处理从位置开始的范围`1`因为`pref[0]`存在。 

现在考虑覆盖整个字符串的范围：```
3 1
zzz
1 3
```前缀数组是：```
pref = [0, 26, 52, 78]
```查询结果为：```
78 - 0 = 78
```全范围查询不需要特殊处理。 

最后，考虑一个以最后一个字符结束但不从第一个字符开始的查询：```
5 1
abcde
3 5
```前缀和为：```
[0, 1, 3, 6, 10, 15]
```答案变成：```
15 - 3 = 12
```这等于`3 + 4 + 5`。 这证实了减去`pref[l - 1]`完全删除不需要的前缀并仅留下请求的子字符串贡献。
