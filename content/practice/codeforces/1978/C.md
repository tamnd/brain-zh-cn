 ## 解决方案
 ## 问题理解

 我们被要求构造一个整数排列$1$到$n$使得每个元素的值与其位置之间的绝对差之和等于给定数字$k$。 正式来说，如果$p$是排列，我们想要$\sum_{i=1}^{n} |p_i - i| = k$。 输入提供多个测试用例，每个测试用例都有一个$n$和一个$k$，我们必须要么产生一个达到精确总和的排列，要么报告不存在这样的排列。 

第一个洞察来自于约束。 和$n$一样大$2 \cdot 10^5$直至$10^4$测试用例中，任何具有二次复杂度的算法都是立即不可行的。 每个测试用例我们都需要一个线性或线性算术方法。 当我们反转排列时，会出现最大可能的曼哈顿值：$n = 5$,$[5,4,3,2,1]$给出$|5-1| + |4-2| + |3-3| + |2-4| + |1-5| = 4+2+0+2+4 = 12$。 这表明可实现的曼哈顿值的范围是$[0, n(n-1)/2]$，这使我们能够快速检测不可能的情况。 

边缘情况出现时$k$非常小 (0) 或非常大（超出第一个的总和$n-1$整数）。 例如，如果$n=1$， 仅有的$k=0$是可能的。 为了$n=3$, 请求的$k=4$是可行的$[3,1,2]$， 但$k=5$是不可能的，因为没有任何排列可以产生这个总和。 对于大的情况，尝试所有排列的天真的方法会默默地失败$n$由于时间有限，所以我们必须找到一种有建设性的、直接的方法。 

## 方法

 暴力解决方案很简单：枚举所有$n!$的排列$1$到$n$，计算每个的曼哈顿值，并检查它是否匹配$k$。 虽然对于小尺寸来说是正确的$n$，这是指数慢的。 为了$n = 10$， 有$3.6 \cdot 10^6$排列； 为了$n = 20$，计数超过$2 \cdot 10^{18}$。 显然，这是不可行的。 

关键的见解来自于观察，将较大的数字放置在远离其自然位置的地方可以最大化局部的绝对差异。 例如，交换第一个和最后一个元素会产生这些位置的曼哈顿值的最大可能增量。 这一观察结果提出了一种贪婪策略：我们可以从左到右构建排列，决定在每个位置是放置最小的剩余数（最小贡献）还是最大的剩余数（最大贡献）。 在每一步中，如果剩余的曼哈顿值允许，我们都会选择最大的可用数字，否则我们会选择最小的数字。 这保证了我们可以达到任何可行的目标$k$在线性时间内。 

这个故事是这样的：暴力破解之所以有效，是因为它通过详尽的检查来保证正确性，但由于阶乘增长而失败。 一旦已知可用数字的范围，就可以认识到每个数字的贡献是独立于其他数字的，从而允许进行贪婪构造。 我们将棘手的搜索简化为基于剩余的本地决策序列$k$，这是线性的$n$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 贪心建设| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算长度的最大可能曼哈顿值$n$，即$n(n-1)/2$。 如果$k$超过此值，立即返回“否”，因为没有排列可以实现它。 
2.初始化两个指针：`low = 1`和`high = n`，代表最小和最大未使用的数字，以及一个空数组`perm`。 
3. 迭代位置$i = 1$到$n$。 在每个位置，对剩余曼哈顿值的最大贡献为`high - i`如果我们放置`high`在这个位置。 
4.如果`k >= high - i`, 附加`high`到`perm`, 递减`k`经过`high - i`，并递减`high`。 这就用最大的数字来吸收尽可能多的曼哈顿价值。 
5. 否则，附加`low`到`perm`, 增量`low`1.放置最小的数字对曼哈顿价值的贡献最小，为剩余位置的调整留下空间。 
6. 继续，直到所有位置都被填满。 最后，如果`k`不为零，说明出了问题； 否则，返回“Yes”并构造`perm`。 

为什么有效：在每一步，我们要么最大化或最小化曼哈顿贡献，而不超出剩余目标`k`。 不变的是剩余的`k`总是可以用剩余的数字来实现，确保正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        max_k = n * (n - 1) // 2
        if k > max_k:
            print("No")
            continue
        
        perm = []
        low, high = 1, n
        for i in range(1, n + 1):
            if k >= high - i:
                perm.append(high)
                k -= high - i
                high -= 1
            else:
                perm.append(low)
                low += 1
        print("Yes")
        print(" ".join(map(str, perm)))

if __name__ == "__main__":
    solve()
```代码直接实现了贪心算法。`max_k`检查可行性。`low`和`high`管理可用号码。 在每次迭代中，我们根据是否可以使用最大的可用数字“花费”剩余的曼哈顿值来决定放置哪个数字。 的选择`high`或者`low`确保剩余的`k`仍然可达。 通过仔细计算可以避免相差一的错误`high - i`并在放置后更新指针。
