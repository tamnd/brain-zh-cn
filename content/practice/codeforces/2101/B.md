 ## 解决方案
 ## 问题理解

 我们得到了一个排列，我们可以将其视为一排不同编号的图块。 唯一允许的移动采取四个连续位置的任何块，并将第一个与第三个、第二个与第四个交换，从而有效地转动一段`[a_i, a_{i+1}, a_{i+2}, a_{i+3}]`进入`[a_{i+2}, a_{i+3}, a_i, a_{i+1}]`。 

任务是理解在重复应用这一举措的情况下可达到的所有排列，然后选择其中字典顺序最小的一个。 

关键的困难在于该操作不是通常的相邻交换意义上的本地操作。 它一次将元素移动两个位置，并保留从语句中不能立即明显看出的某种结构。 

从约束来看，所有测试用例的总长度最多为2·10^5，因此任何模拟操作甚至探索大状态空间的解决方案都是不可能的。 每个测试用例的时间复杂度大约为 O(n log n) 或 O(n)。 

一个天真的错误是假设此操作允许任意排序甚至任意相邻交换。 例如，在像这样的小情况下`[3,4,1,2]`，人们可能会错误地认为我们可以自由地重新排序所有内容，但实际上该操作保留了更深层次的不变量，限制了哪些元素可以交互。 

另一个微妙的陷阱是认为该操作独立地作用于原始数组中的偶数和奇数位置。 这种直觉很接近但不完整，因为每个操作都根据索引而不是位置值在奇偶校验类之间移动元素。 

## 方法

 暴力视图首先将排列视为图中的一种状态，其中边连接通过一个有效操作可到达的配置。 每次移动都会重新排列四个元素，因此每个状态最多有 O(n) 次转换。 BFS 或 DFS 最终将探索所有可达的排列并按字典顺序选择最小的排列。 

这在原则上是正确的，但状态空间的大小是阶乘的。 即使对于n = 10，可达状态的数量也会变得巨大，而对于n = 2·10^5，这是完全不可行的。 

关键的观察是停止考虑全球重新安排，而是检查该行动保留了什么。 每个操作都会交换对`(i, i+2)`和`(i+1, i+3)`，这意味着元素始终在两个独立的索引类内移动：具有相同奇偶校验（偶数或奇数索引）的位置永远不会混合。 

更准确地说，最初位于奇数索引中的元素只能移动到奇数索引，对于偶数索引也是如此。 这是因为每次交换都会将元素恰好移动两个位置。 结果，排列分解为两个独立的子序列：奇数位置上的元素和偶数位置上的元素。 

在每个奇偶校验类中，该操作等效于能够交换该子序列的相邻元素。 对原始数组的单个操作会交换压缩奇偶校验序列中的两个相邻元素。 这将问题简化为：我们可以独立地对每个奇偶校验子序列进行排序。 

为了获得按字典顺序排列的最小完整数组，我们对奇数位置的元素进行排序，对偶数位置的元素进行独立排序，然后将它们交错回来。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（状态图）| O(n!) | O(n!) | 太慢了|
 | 奇偶分解+排序| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 将数组拆分为两个序列：一个序列包含位置 1、3、5、... 的元素，另一个序列包含位置 2、4、6、... 的元素。 
2. 对每个序列进行独立排序。 这是合理的，因为在每个奇偶校验类中，重复操作允许我们将元素自由地重新排列为相邻交换可实现的任何顺序，这足以进行排序。 
3. 通过将已排序的奇数位置序列放回索引 1、3、5、... 并将已排序的偶数位置序列放回索引 2、4、6、... 来重建最终数组。 
4. 输出重构后的数组。 

排序有效的原因是允许的操作可以模拟每个奇偶校验序列内相邻元素的交换，因此奇偶校验子序列在相邻转置下形成独立的排列组。 

### 为什么它有效

 不变的是每个元素都保留索引奇偶性。 任何操作都不会将元素从奇数索引移动到偶数索引，反之亦然。 在每个奇偶校验类中，该操作充当相邻交换的生成器，已知该生成器会在该子集上生成完整的对称组。 因此，每个奇偶校验子序列的每个排列都是可达的，并且通过对两个子序列独立排序来实现字典序上最小的全局排列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        odd = a[0::2]
        even = a[1::2]
        
        odd.sort()
        even.sort()
        
        res = []
        i = j = 0
        
        for k in range(n):
            if k % 2 == 0:
                res.append(odd[i])
                i += 1
            else:
                res.append(even[j])
                j += 1
        
        print(*res)

if __name__ == "__main__":
    solve()
```该实现依赖于切片以分离奇偶校验类。 排序步骤是捕获每个类中所有可达配置的核心转换。 重建交替元素以恢复原始索引结构。 

一个常见的实现陷阱是将基于 0 的索引逻辑与基于 1 的奇偶校验推理混合在一起。 这里，索引 0 对应于问题中的位置 1，因此代码中的偶数索引对应于语句中的奇数位置。 

## 工作示例

 ### 示例 1

 输入：```
4
3 4 1 2
```我们分为奇偶校验类别：

 | 步骤| 奇怪的位置 | 偶数职位|
 | --- | --- | --- |
 | 初始| [3, 1] | [4, 2] |
 | 已排序 | [1, 3] | [2, 4] |

 重建：

 | 索引 | 来源 | 价值|
 | --- | --- | --- |
 | 1 | 奇数| 1 |
 | 2 | 甚至| 2 |
 | 3 | 奇数| 3 |
 | 4 | 甚至| 4 |

 输出是`[1, 2, 3, 4]`。 

这证实了单个操作足以实现奇偶校验组内的完全重新排列。 

### 示例 2

 输入：```
5

```拆分：

 | 步骤| 奇怪的位置 | 偶数职位|
 | --- | --- | --- |
 | 初始| [5,3,2]| [4, 1] |
 | 已排序 | [2,3,5]| [1, 4] |

 重建：

 | 索引 | 价值|
 | --- | --- |
 | 1 | 2 |
 | 2 | 1 |
 | 3 | 3 |
 | 4 | 4 |
 | 5 | 5 |

 输出是`[2, 1, 3, 4, 5]`。 

这展示了全局排序如何纯粹从独立奇偶排序中产生。

 ## 边缘情况

 一种重要的边缘情况是当 n 最小时，例如 n = 4。在这种情况下，只能进行一种操作，但奇偶分解仍然完全确定答案。 用于输入`[3,4,1,2]`, 分裂产生赔率`[3,1]`甚至`[4,2]`，排序给出`[1,3]`和`[2,4]`，重建产生`[1,2,3,4]`，匹配单个允许操作可达到的最佳结果。 

另一种微妙的情况是当一个奇偶校验类的大小为 1 时。例如，`n = 5`并输入`[5,4,3,2,1]`。 奇数位置是`[5,3,1]`，甚至位置是`[4,2]`。 排序独立进行，重建遵循固定的奇偶位置。 即使最小的元素可能从偶数索引开始，它也不能跨越奇数索引，并且该算法正确地保留了此限制。
