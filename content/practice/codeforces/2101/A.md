 ## 解决方案
 ## 问题理解

 我们被要求填写一个$n \times n$网格中的整数$0$到$n^2 - 1$，每个只使用一次。 每个矩形子网格贡献的值等于其内部数字的 MEX，目标是在所有可能的子矩形上最大化这些 MEX 值的总和。 

关键的困难不是计算固定网格的 MEX，而是选择数字的位置，以便许多子网格包含较小的值，例如$0, 1, 2, \dots$尽可能频繁地使用，因为这些是唯一可以增加 MEX 的值。 大数字实际上是惰性的：除非所有较小的数字都已经存在，否则它们永远不会帮助增加 MEX。 

约束条件允许$n$最多 500 个，所以$n^2$可以达到25万。 任何模拟子网格或直接计算每个子网格 MEX 的解决方案都将大致涉及$O(n^4)$或者$O(n^3)$操作，这远远超出了可行性。 甚至$O(n^2 \log n)$结构很好，但排除了每个子网格的任何原因。 

当数字随机分散或按行优先顺序放置时，会出现微妙的失败情况。 例如，对于$n=3$，放置：```
0 1 2
3 4 5
6 7 8
```对仅聚集在左上角区域的小值产生强烈的偏见。 许多可能包含小值的子网格完全忽略了它们，从而减少了 MEX 的贡献。 相反，最佳排列必须确保小值被分散，以便许多子矩形尽早包含它们。 

## 方法

 一个蛮力的想法是尝试所有的排列$n^2$数字并计算每个排列的 MEX 总和。 根据定义这是正确的，但不可能，因为有$(n^2)!$排列，并且评估每一个都需要迭代所有排列$O(n^2)$子网格最多可达$O(n^2)$每个子网格的工作，至少导致$O((n^2)! \cdot n^4)$复杂。 

我们需要进行结构观察：MEX 完全由早期小数字在矩形内出现的方式驱动。 对于固定子网格，其 MEX 至少为$k$当且仅当所有数字$0$通过$k-1$都在里面。 那么每个值的贡献$x$取决于有多少子网格包含所有数字$0 \dots x-1$。 

这重新构建了问题：我们不想直接考虑 MEX，而是希望放置小数字，以便集合$\{0,1,\dots,x\}$往往位于许多矩形中。 

最大化此值的经典方法是将小值聚集在紧凑区域中，因为紧密聚集比分散配置包含更多的子矩形。 最佳策略是构建“蛇状”或螺旋状排序，以便任何数字前缀在空间上保持紧凑。 

一种简单的最佳构造是从左上角开始以螺旋状填充网格，逐层向内移动。 这保证了最小的集合$k$数字总是形成一个连接的、大致呈正方形的区域，这使得完全包含它的子矩形的数量最大化。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 |$O((n^2)! \cdot n^4)$|$O(n^2)$| 太慢了|
 | 螺旋/分层结构|$O(n^2)$|$O(n^2)$| 已接受 |

 ## 算法演练

 目标是分配数字$0 \dots n^2-1$以便小值在空间上聚集。 

1.从空开始$n \times n$网格和当前值$v = 0$。 价值$v$将始终代表下一个最小的未使用数字，确保我们控制前缀的几何形状。 
2. 保持四个边界：顶行、底行、左列、右列。 这些定义了当前未填充的矩形。 最初，这些是完整的网格。 
3. 使用当前边界从左到右填充顶行，并分配连续的值。 填充完毕后，将顶部边界向内移动。 这确保最小值占据最外层，使许多矩形可以访问它们。 
4. 从上到下填充右列，然后缩小右边界。 这继续了向内分层，同时保留了小值的连接性。 
5. 从右向左填充底部行，然后缩小底部边界。 
6. 从下到上填充左列，然后缩小左边界。 
7. 重复此过程，直到所有单元格都被填满。 每个完整的周期都会在中心周围创建一个不断增加值的“环”。 

这种排序很重要的原因是值的任何前缀$0 \dots k$总是会形成一个以受控方式向内收缩的连续区域。 这最大化了完全包含前缀的子矩形的数量。 

### 为什么它有效

 对于任何值$k$，考虑包含以下内容的单元格集合$0 \dots k$。 在这种结构中，这些单元总是形成具有最小边界矩形的连接区域。 由于子网格中的 MEX 取决于是否包含所有这些值，因此最大化包含边界矩形的子网格数量可以最大化总贡献。 螺旋确保该边界矩形尽可能缓慢且对称地增长，从而最大化所有可能矩形的包含频率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        grid = [[0] * n for _ in range(n)]
        
        top, bottom = 0, n - 1
        left, right = 0, n - 1
        val = 0
        
        while top <= bottom and left <= right:
            for j in range(left, right + 1):
                grid[top][j] = val
                val += 1
            top += 1

            for i in range(top, bottom + 1):
                grid[i][right] = val
                val += 1
            right -= 1

            if top <= bottom:
                for j in range(right, left - 1, -1):
                    grid[bottom][j] = val
                    val += 1
                bottom -= 1

            if left <= right:
                for i in range(bottom, top - 1, -1):
                    grid[i][left] = val
                    val += 1
                left += 1

        for row in grid:
            print(*row)

if __name__ == "__main__":
    solve()
```该代码实现了标准的螺旋填充。 重要的实现细节是在填充底行和左列之前进行仔细的边界检查。 如果没有这些检查，当螺旋塌陷到中心时，奇数大小的网格将覆盖已经分配的单元格。 

变量`val`严格递增并确保每个数字来自$0$到$n^2-1$仅使用一次。

 ## 边缘情况

 一个最小的网格就像$n=1$仅包含单个值。 算法立即进入循环，用 0 填充单元格 (0,0)，然后终止。 由于循环条件，不会发生边界损坏`top <= bottom and left <= right`只保留一次。 

对于奇数大小的网格，例如$n=3$，螺旋最终塌陷到中心单元中。 在那一刻，所有边界都汇聚在一起，只剩下一个任务。 边界检查可防止重新处理已填充的单元格，确保中心值仅写入一次。
