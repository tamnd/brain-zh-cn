 ## 解决方案
 ## 问题理解

 该任务本质上是在 Connect Four 板上进行“假设”模拟。 我们有一个 6 x 7 的网格来表示游戏的当前状态，其中每个单元格可以包含一个红色块、另一种颜色或为空。 我们还可以尝试按照重力规则将红色棋子放置在任何一列中，这意味着它将占据该列中最低的空单元格。 

对于 7 列中的每一列，如果可能的话，我们模拟将一个红色棋子放入该列中。 下棋后，我们检查这一步棋是否为红方创造了获胜局面。 获胜的定义是四个红色棋子在两个对角方向中的任何一个方向上连续水平、垂直或对角对齐。 如果移动后至少存在一条这样的线，则该列被视为获胜移动。 

输出是列数，如果红色在那里玩，红色立即获胜。 

网格大小固定为 6 × 7，因此状态空间是恒定的。 这意味着即使是检查所有可能性并多次扫描电路板的简单解决方案也已经可行。 关键的约束意味着任何每列最多几千次操作的解决方案都是完全安全的。 

当列已满时，会出现微妙的边缘情况。 在这种情况下，移动无效并且必须被忽略。 另一个边缘情况是，即使棋盘已经包含看起来接近胜利的部分结构，放置一个棋子并不会立即形成四连棋。 如果一个简单的实现在检查后忘记恢复模拟移动，可能会错误地跨列累积状态。 

作为极端情况的示例，请考虑一列，其中放置一个棋子构成四条对角线。 如果我们忘记正确模拟重力，而是将棋子放置在最上面的空单元格中，我们可能会错过有效的胜利。 同样，如果我们在测试列后未能恢复电路板，则后面的检查将被早期的模拟污染。 

## 方法

 直接暴力方法尝试每一列，模拟掉落一个红色棋子，然后扫描整个棋盘以检测是否存在连续的四个红色棋子的序列。 由于棋盘只有 6 x 7 的大小，因此检查所有可能的起始位置和方向是一项持续的工作，但仍对每一列重复进行。 这总共提供了 7 次模拟，每次模拟后都进行全板扫描。 

扫描本身会检查每个单元格作为四个方向的四个序列的潜在起点：右、下、对角线右下和对角线右上。 每次检查都是恒定时间，因此完整扫描也是恒定时间。 因此，暴力解决方案已经很有效，但其结构略有冗余，因为即使只添加了一块新部件，它也会重新检查整个板。 

关键的观察是，如果我们已经有一个可以正确检测棋盘上胜利的函数，那么我们不需要从头开始重新计算所有内容。 由于电路板很小，因此在每次模拟移动后重用此函数比尝试增量维护状态更简单且不易出错。 因此，最好通过使用干净的 win-check 函数进行直接模拟来解决该问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力扫描每一步 | O(7 × 6 × 7) | O(1) | O(1) | 已接受 |
 | 模拟 + 全面获胜检查 | O(7 × 6 × 7) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将棋盘视为一个固定网格，并重复模拟在每列中放置一个红色棋子。

1. 读取 6 x 7 棋盘并将其存储为可变网格。 这允许我们在模拟过程中临时修改它，而无需分配新的结构。 
2. 定义一个辅助函数，检查红色是否在棋盘上的任何位置都有获胜线。 该函数扫描每个单元格并检查四个方向：水平向右、垂直向下、对角线右下和对角线右上。 每次检查都会确保在比较四个连续单元格之前索引保持在范围内。 检查所有单元格的原因是，任何获胜段都必须从该段的某个最左上角的单元格开始，至少在一个方向上。 
3. 初始化有效获胜动作的计数器。 
4. 迭代 7 列中的每一列，将每一列视为候选移动。 
5. 对于每一列，通过从底行向上扫描来模拟重力，直到找到第一个空单元格。 如果不存在空单元格，则该列已满，我们将跳过它。 此步骤可确保棋子准确地落地，就像在实际游戏中一样。 
6. 暂时将红色棋子放入找到的单元格中。 
7. 在更新后的板上运行 win-check 功能。 如果返回 true，则增加答案计数器，因为此举会立即获胜。 
8. 取下模拟件，恢复原板状态。 这一点至关重要，因为每根色谱柱都必须独立测试。 
9. 测试完所有列后，输出计数器。 

### 为什么它有效

 该算法依赖于模拟和评估之间的严格分离。 每列都在其他未改变的板上进行单独测试。 获胜检查功能详尽地涵盖了所有可能的起点和方向，因此如果移动后存在任何四连胜，无论它出现在哪里，都会被检测到。 由于每个可能的合法动作都被精确地模拟一次，因此每个获胜的动作都被精确地计算一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def win(field):
    for row in range(6):
        for col in range(7):
            if col + 3 < 7:
                if field[row][col] == field[row][col+1] == field[row][col+2] == field[row][col+3] == 'R':
                    return True
            if row + 3 < 6:
                if field[row][col] == field[row+1][col] == field[row+2][col] == field[row+3][col] == 'R':
                    return True
            if col + 3 < 7 and row + 3 < 6:
                if field[row][col] == field[row+1][col+1] == field[row+2][col+2] == field[row+3][col+3] == 'R':
                    return True
            if col + 3 < 7 and row - 3 >= 0:
                if field[row][col] == field[row-1][col+1] == field[row-2][col+2] == field[row-3][col+3] == 'R':
                    return True
    return False

field = [list(input().strip()) for _ in range(6)]

ans = 0

for col in range(7):
    row = 5
    while row >= 0 and field[row][col] != '.':
        row -= 1

    if row < 0:
        continue

    field[row][col] = 'R'

    if win(field):
        ans += 1

    field[row][col] = '.'

print(ans)
```该解决方案首先定义获胜检测例程。 每个方向都通过边界检查显式处理，以便索引不会超出范围。 该逻辑在水平、垂直和对角线情况下是对称的，确保检测的完整性。 

主循环独立尝试每一列。 重力模拟是通过简单的向下扫描来完成的，考虑到板的高度恒定，这是最佳的。 放置好部件后，我们立即评估电路板，然后将其恢复。 此回滚步骤可防止迭代期间的状态泄漏。 

一个常见的陷阱是在测试色谱柱后忘记恢复单元。 这将导致以后的模拟假设已经存在额外的红色碎片，从而产生错误的结果。

 ## 边缘情况

 完整的列是最简单的结构边缘情况。 该算法通过向上扫描直到找不到空单元格来处理它，然后跳过该列。 这确保了我们永远不会非法放置棋子。 

第二种边缘情况是在任何行动之前已经存在胜利。 该问题仍然要求在放置后创建获胜的移动，因此我们只计算模拟移动导致获胜状态的列。 每次模拟排名后都会应用获胜检查功能，因此预先存在的获胜不会干扰计数。 

第三种边缘情况是棋盘边界处的对角完成。 例如，结束于第 0 行或第 5 行的对角线需要仔细的边界检查。 该实现在比较四个单元之前明确保护索引访问，确保没有无效的内存访问和没有丢失的配置。
