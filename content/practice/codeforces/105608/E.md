 ## 问题理解

 我们得到一个仅由零和一组成的二进制字符串。 在一个操作中，我们采用一对相邻字符并应用类似 XOR 的规则，根据简单的本地交互将它们压缩为单个字符。 如果两个字符都是 1，则它们会消减为 0。 如果其中至少一个为零，则该零消失，而另一个字符幸存。 

重复该过程，逐步缩小字符串，直到整个字符串变得均匀，这意味着所有剩余字符都为零或所有剩余字符都是一。 任务是确定达到这两个最终状态中的任何一个所需的此类操作的最少数量。 

重要的结构约束是操作是局部的并合并相邻元素，因此成本不在于独立计算字符，而在于如何通过邻接变换将它们配对和消除。 

如果字符串的长度达到十万左右，任何尝试逐步模拟操作的解决方案都将失败，因为每个操作都会将长度减少一，但可能需要线性或更差的工作来决定，从而在最坏的情况下导致二次行为。 这迫使我们寻找一种仅依赖于计数和线性扫描的解决方案。 

当 1 的数量为奇数时，会出现微妙的边缘情况。 在这种情况下，不可能通过配对来消除所有 1，因为每次删除 1 的操作都会成对消耗它们。 例如，在像这样的字符串中`101`，没有办法以全零结束，因为无论零在其周围如何重新排列，都必须保留一个未配对的1。 任何假设我们总是可以归零的幼稚策略都会在这里失败。 

当字符串已经统一时，会出现另一个极端情况。 如果全为零，则需要进行零运算。 如果全为1且长度为偶数，仍然需要配对逻辑； 如果是奇数，则立即排除全零目标。 

## 方法

 直接模拟将尝试重复扫描字符串，选择相邻对，应用 XOR 规则，重建字符串，并继续直到实现一致性。 这在原则上是正确的，因为它完全遵循允许的操作。 然而，每个操作都需要更新动态结构，并可能再次扫描有效对，当字符串很大并且频繁减少时，这会导致二次或更糟糕的行为。 

关键的观察结果是，该过程实际上并不是关于不断演变的字符串，而是关于如何以最佳方式匹配和删除字符。 只有两个有意义的目标：以全 1 结尾或以全 0 结尾，我们可以独立评估这两个目标。 

将一切转化为一个很简单。 每个零都可以通过将其与包含至少一个零的任何相邻元素配对来消除，从而有效地允许单独删除每个零。 这意味着达到所有 1 的成本正是 0 的数量。 

将一切都转化为零更加结构化。 个体不能单独消失； 它们必须成对删除，因为只有两个相互作用才会产生零。 这立即意味着，如果 1 的数量是奇数，则该目标是不可能的。 

当数量为偶数时，最佳策略是按照出现的顺序进行配对。 我们列出 1 的所有索引，并将第一个与第二个、第三个与第四个配对，依此类推。 每对的成本等于它们之间有多少个零，因为在此过程中必须“绕过”或消除这些零。 对这些间隙求和就得到了总移动成本，每对消耗两个，因此配对贡献的操作数量是 1 数量的一半。 

蛮力之所以有效，是因为它显式模拟本地合并，但当字符串很大时会失败。 只有一个人的相对位置才重要的观察结果可以简化为线性扫描和简单的索引算术。

 | --- | --- | --- | --- |
 | 暴力模拟| O(n²) | O(n) | 太慢了 |

 ## 算法演练

 1. 计算字符串中有多少个零。 这立即给出了将所有内容转换为 1 的成本，因为每个零都可以通过有效的本地操作序列独立删除。 
2. 扫描一次字符串，收集列表中所有索引。 这是必要的，因为所有进一步的推理仅取决于 1 的相对位置，而不是 0。 
3. 仅当 1 的数量为偶数时才计算转换为 0 的成本。 如果很奇怪，请完全跳过此分支，因为不可能将所有分支配对。 
4. 如果个数是偶数，则取出索引列表并按顺序将连续的个数配对。 对于每一对，计算它们之间的零数，即索引差减一。 
5. 对所有对的这些间隙值求和。 这代表着将成对的个体聚集在一起以便它们能够消灭所需的额外工作。 
6. 将一半的 1 数量添加到该总和中，因为每一对 1 在组合在一起后仅在一次操作中被删除。 
7. 取将一切变为 1 的成本和将一切变为 0 的成本之间的最小值。 

正确性依赖于这样一个事实：最佳配对必须保持顺序。 任何交叉配对只会增加距离，从而增加成本，因此按索引顺序相邻配对是最佳的。

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    
    zeros = s.count('0')
    ones_positions = []
    
    for i, ch in enumerate(s):
        if ch == '1':
            ones_positions.append(i)
    
    ans = zeros
    
    if len(ones_positions) % 2 == 0:
        cost = 0
        for i in range(0, len(ones_positions), 2):
            cost += ones_positions[i+1] - ones_positions[i] - 1
        cost += len(ones_positions) // 2
        ans = min(ans, cost)
    
    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先计算使用单个线性计数将所有字符转换为字符的简单目标。 然后，它一次性构建 1 的位置列表。 条件块确保仅在有效时尝试零目标计算。 

配对循环以 2 为增量进行，确保每个循环都恰好参与一对。 减法`ones_positions[i+1] - ones_positions[i] - 1`正确地仅计算配对之间严格的零。 

## 工作示例

 ### 示例 1

 输入：```
5
10101
```我们扫描字符串并记录位置`[0, 2, 4]`。 共有三个 1，这是奇数，因此将所有内容都转换为零的策略是无效的。 

0 的数量是 2，因此将所有内容转换为 1 的成本是 2。 

由于零目标是不可能的，所以答案是2。 

这显示奇偶校验如何立即禁用一个分支。 

### 示例 2

 输入：```
6
110100
```我们首先计算零：有 3 个零，因此生成所有零的成本为 3。 

的位置是`[0, 1, 3]`。 有 3 个，又是奇数，所以零目标是无效的。 

答案是3。 

现在考虑修改后的情况：```
6
110011
```职位有`[0, 1, 4, 5]`。 

| 配对| 左索引| 右索引| 间隙（零）|
 | --- | --- | --- | --- |
 | 1 | 0 | 1 | 0 |
 | 2 | 4 | 5 | 0 |

 间隙总和为 0，对数为 2，因此配对成本为 2。 

全部为 1 的成本是零的数量，也是 2。最终答案是 2。 

这表明紧密聚集的企业如何最大限度地降低移动成本。

 ## 边缘情况

 单字符字符串，例如`0`已处于有效的最终状态。 该算法将 0 算作 1，但仍然采用配对成本为零的最小值，因为没有 0，因此结果正确地变为 0。 

对于像这样的字符串`111`，个数为奇数，因此跳过配对分支。 只剩下将所有零转换为一的成本，该成本为零，因为没有零。 因此，即使简单的配对尝试会错误地假设可行性，该算法也会正确返回零。 

对于像这样紧密排列的字符串`11110000`，这些是连续的，因此配对之间的所有间隙为零。 成本纯粹减少到对的数量，确认移动成本仅取决于零分隔而不是绝对位置。
