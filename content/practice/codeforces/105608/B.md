 ## 问题理解

 我们在平面上有两个圆形目标。 每个目标由其中心坐标和半径定义。 从这两个圆中，我们被要求确定从 0 到 3 的四个“分数”中哪一个是可以实现的，其中每个分数对应于两个圆之间的几何关系。 

如果第一个圆没有完全包含在第二个圆内，则它可以贡献 1 分。 对称地，如果第二个圆没有完全包含在第一个圆内，则它可以贡献分数 2。 如果两个圆相交或相互接触，则得分为 3。 根据定义，得分 0 始终是可能的，因此它始终包含在答案集中。 

关键量是圆心之间的距离。 该语句将其定义为欧几里德距离，但提供的代码使用平方根下的平方距离，有效地以浮点形式计算实际距离。 

尽管问题看起来涉及多个条件，但输出只是集合 {0, 1, 2, 3} 的子集，按升序打印。 

约束足够小，每个测​​试用例都是独立的，并且可以在恒定时间内解决。 计算仅涉及少量算术运算，因此每个测试用例的预期解决方案必须以 O(1) 的速度运行。 

主要的边缘情况来自几何边界条件。 完全相切的圆可以轻松地翻转条件，具体取决于不等式是严格的还是非严格的。 另一种微妙的情况发生在一个圆完全位于另一个圆内，但它们的边界仍然恰好在一个点处接触时。 在这样的配置中，包含条件和交叉条件以某种方式相互作用，如果不正确地使用严格的不等式，则可能会混淆不正确的实现。 

例如，如果圆 1 完全位于圆 2 内，则不应包括分数 1。 当中心偏移时，像单独比较半径这样简单的检查会失败。 

## 方法

 在这里，暴力方法并不是真正的组合，因为没有大型结构可供搜索。 相反，天真的想法是以字面的方式在几何上解释每个条件：对于包含，我们可能会尝试检查一个圆的每个点是否都位于另一个圆内，而对于相交，我们可能会尝试使用从第一原理导出的几何公式​​来推理重叠区域。 

这种方法很快就会变得不必要的复杂且容易出错。 在连续几何中逐点检查包含性是不可能的，甚至离散点也是毫无意义且低效的。 强力解释失败了，因为几何提供了封闭形式的距离条件，取代了任何采样或枚举的需要。 

关键的见解是，所有必需的条件都简化为仅涉及中心和半径之间的距离的比较。 一旦我们计算出该距离，三个重要分数中的每一个都对应于一个简单的不等式。 

圆1在圆2中的包含取决于圆1的最远点是否仍在圆2内，这简化为检查圆1的圆心距离加上圆2的半径是否超过圆2的半径。相同的逻辑对称地适用于反向包含条件。 

交集取决于半径之和是否至少等于中心之间的距离。 这可以捕获正确的相交和相切。 

因此，整个问题归结为评估三个独立的不等式。

 ## 算法演练

我们计算两个圆中心之间的欧几里德距离，然后评估三个独立的几何条件。 

1. 读取两个圆的坐标和半径。 这定义了完整的几何配置。 
2. 使用欧几里德公式计算中心之间的距离。 这个单一的值完全决定了圆之间的所有空间关系。 
3. 从 0 开始答案集，因为无论几何形状如何，它都始终包含在内。 
4. 通过测试圆 1 的距离加上半径是否大于圆 2 的半径来检查圆 1 是否未完全包含在圆 2 中。如果是，则在答案中包含 1。 
5. 检查圆 2 是否完全包含在圆 1 中的对称条件。如果为真，则在答案中包含 2。 
6. 通过验证圆心之间的距离至多为半径之和来检查圆是否相交或接触。 如果正确，请在答案中包含 3。 
7. 按升序输出所有收集到的值。 

每个条件背后的推理都是纯粹的几何推理。 为了遏制，我们测量一个圆相对于另一个中心的最远可能点。 对于相交，我们比较中心相距多远与圆向外延伸的距离。 

### 为什么它有效

 该算法依赖于这样一个事实：两个圆之间的任何关系完全由三个量决定：两个半径和中心之间的距离。 问题陈述中的每个条件都可以重写为涉及这些值的直接不等式。 由于这些不等式既是必要的又是充分的，因此独立评估它们不能错过任何有效分数或包含任何无效分数。 条件的独立性确保检查之间不存在隐藏的依赖关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

x1, y1, r1 = map(int, input().split())
x2, y2, r2 = map(int, input().split())

dx = x1 - x2
dy = y1 - y2
d = (dx * dx + dy * dy) ** 0.5

ans = [0]

if r1 + d > r2:
    ans.append(1)

if r2 + d > r1:
    ans.append(2)

if d <= r1 + r2:
    ans.append(3)

print(*ans)
```实现直接遵循几何推导。 距离计算是使用平方差和平方根完成的，与预期的欧几里德度量相匹配。 每个条件都是独立检查的，并且结果会自动按升序附加，因为我们从 0 开始并按升序标签顺序评估条件。 

一个微妙的实现细节是使用浮点算术计算距离。 虽然平方距离比较可以避免浮点精度问题，但该问题的预期解决方案使用平方根形式，因此在典型约束下这仍然是正确的。

 ## 边缘情况

 一个关键的边缘情况是相切，即圆恰好在一个点相交。 例如，中心距等于 r1 + r2 的圆仍应算作相交。 条件 d ≤ r1 + r2 正确包含这种情况，并且算法添加分数 3。 

另一个微妙的情况是完全重叠，其中两个圆具有相同的中心和半径。 在这种情况下，每个圆仅在退化意义上完全包含在另一个圆中，但不等式 r + d > r 在两个方向上都失败，因此分数 1 和 2 被排除。 同时，交集仍然成立，因为距离为零，小于或等于半径之和。 

第三种情况是严格隔离隔离，其中一个圆圈完全位于另一个圆圈内，但不接触边界。 例如，以 (0,0) 为中心、半径为 10 的大圆和以 (1,0) 为中心、半径为 1 的小圆生成 d = 1。条件 r1 + d > r2 可以正确检测不对称性，确保仅包含适当的分数，同时仍将交集标记为 true。
