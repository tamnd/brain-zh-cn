 ## 解决方案
 ## 问题理解

 我们得到两个整数，它们表示应用于小写拉丁字母字符串的某些隐藏编码过程的期望结果。 每个字母都会贡献两个累积值 A 和 B，但方式略有不对称：每个字符使 B 增加的值恰好比 A 增加的值多 1。换句话说，与 A 相比，B 从每个字母中获得额外的贡献单位。 

从这种关系中，出现了关键的简化。 如果字符串的长度为 L，则 B 始终恰好为 A + L。这会立即消除一个自由度，并将任务转变为检查是否存在某种长度的一致字符串，然后如果存在则构造一个字符串。 

字符串本身通过通常的字母表索引对 A 做出贡献，其中字母的行为类似于 0 到 25 范围内的权重。像这样的字母`a`贡献 0,`b`贡献 1，并且`z`贡献 25。B 不直接依赖于这些权重，仅依赖于每个字符存在的事实。 

因此，任务变成：选择长度 L 和 L 字母，使它们的权重之和等于 A，同时也尊重 B 必须等于 A + L。由于给定了 B，L 被迫为 B − A。这消除了选择长度的任何自由。 

然后问题就简化为决定我们是否可以将 A 表示为 L 值的总和，每个值都在 0 到 25 之间（含），如果可以，则构造这样一个序列。 

输入约束意味着我们正在一个 L 足够大的机制中工作，以至于暴力破解所有字符串是不可能的。 即使对于中等 L，枚举所有组合也会呈指数爆炸。 因此，任何有效的解都必须在 L 中是线性的。 

当可行性失败时，就会出现边缘情况。 如果 L 小于 1，则不存在有效字符串，因为我们无法构造非正长度序列。 当 A 太大而无法分布在 L 个字符上时，就会出现另一种失败情况，这意味着即使每个字符都是`z`，我们无法达到 A。该上限为 25 × L。同样，A 不能为负数或超过每个字符限制下可实现的值。 

一个简单的例子说明了故障情况。 如果A是10，L是1，那么我们需要一个角色贡献10，这是不可能的，因为最大值是25，所以这个实际上很好； 更好的例子：如果A是30，L是1，这是不可能的。 相反，如果 A 为 0，L 为 1，我们可以使用`a`。 

## 方法

 暴力方法会尝试构建长度为 L 的字符串，并尝试每种可能的字母分配，检查它们的权重总和是否等于 A。这在概念上很简单，因为它直接反映了约束定义。 然而，每个位置有 26 个选择，因此搜索空间为 26^L，即使 L 约为 20，这也是不可行的。 

问题的结构允许更强有力的观察。 我们不关心字母的排列，只关心是否可以将 A 分解为 L 个有界部分。 这是一个经典的有界组合问题，但具有非常具体的贪婪结构：只要我们保持在剩余容量范围内，尽早取较大的值就不会限制未来的可行性。 

这允许贪婪的构造。 由于每个角色最多可以贡献 25 个，因此我们尝试在每个步骤中分配尽可能多的值，首选`z`每当我们仍然需要较大的 A 值时。如果剩余的 A 小于 25，我们将准确放置所需的内容，并通过隐式用零填充其余部分`a`。 

正确性来自于这样一个事实：只要初始可行性成立，在每一步将 A 减少最大可能值即可使我们保持在可行区域内。

 ## 算法演练

 我们首先将问题转换为长度和可行性检查，然后贪婪地构造字符串。 

1. 计算所需的长度 L 为 B − A。这直接从观察中得出，与 A 相比，每个字符为 B 贡献了一个额外的单位，因此 B 始终是 A 加上字符数。 
2. 检查L是否至少为1。如果不是，则不存在字符串，因为我们无法形成负长度或零长度的非空序列。 
3. 检查 A 是否位于相对于 L 的可行范围内，特别是在 0 到 25 × L 之间。下限确保我们不需要负贡献，上限确保甚至最大化所有字符：`z`不超过A。 
4. 如果可行性条件不满足，则立即输出-1。 
5. 初始化一个空结果字符串，并精确迭代 L 次，从左到右逐个字符地构建字符串。 
6. 在每一步中，选择当前角色的贡献为 min(25, 剩余 A)。 这是我们在不超过剩余要求的情况下可以安全分配的最大可能值。 
7. 通过偏移量将此数字贡献转换为字符`'a'`，将其附加到结果中，然后从 A 中减去它。 
8. 继续，直到所有位置都被填满。 最后，A 变为零，这意味着贡献的总和与所需的值完全匹配。 

为什么它起作用是基于维护一个简单的不变量：在每一步之后，剩余的 A 总是可以用剩余的字符数来实现，因为我们永远不会将 A 减少到零以下，并且每个字符永远不会消耗超过 25 个字符。 由于初始可行性保证 A ≤ 25 × L，贪婪的最大消耗不能阻止未来的步骤。 任何剩余值始终是可分配的，因为每个步骤都保留条件 A ≤ 25 ×剩余长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

a = int(input())
b = int(input())

length = b - a

if length < 1 or a < 0 or a > 25 * length:
    print(-1)
    sys.exit()

ans = []

for _ in range(length):
    take = min(25, a)
    ans.append(chr(ord('a') + take))
    a -= take

print(''.join(ans))
```实现首先从 A 和 B 之间的关系导出强制长度。可行性检查确保当目标总和 A 无法分布在可用字符数上时，我们不会尝试构造。 

贪心循环是解决方案的核心。 每次迭代都会消耗最大可能的贡献，同时遵守上限 25。转换`chr(ord('a') + take)`将数字权重映射回字母。 

一个微妙之处是确保 A 永远不会变为负值，这是通过 min 操作来防止的。 另一个是我们永远不需要回溯，因为可行性保证贪婪的选择总是留下有效的余数。

 ## 边缘情况

 当 B 等于 A 时，计算出的长度变为零。 该算法会立即拒绝这种情况，因为有效的字符串必须至少包含一个字符。 对于输入 A = 10、B = 10，我们得到 L = 0，并且输出为 -1，因为不存在构造。 

当 A 相对于 L 非常大时，例如 A = 100 且 L = 3，可行性检查会失败，因为即使是 3`z`字符仅贡献 75。算法在尝试构建之前正确停止。 

当 A 为零时，构造退化为所有`a`人物。 对于 A = 0 和任何有效的 L，每次迭代都取 0，产生权重中的一串零，这对应于重复`a`。
