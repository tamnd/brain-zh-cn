 ## 解决方案
 ## 问题理解

 鱼从坐标开始`0`在无限轴上并且想要精确着陆在坐标处`K`。 通过选择三种跳跃类型之一来进行移动。 第一次选择类型时，它会跳转自己的编号（`1`,`2`， 或者`3`）。 以后每次使用相同类型都会将该类型之前的跳跃长度增加`3`。 

该任务有两个部分。 我们需要能够达到的最小跳跃次数`K`，我们还需要达到的不同选择序列的数量`K`，无论这些序列使用了多少次跳跃。 第二个答案需要模数`10^9 + 7`。 官方的限制是`K <= 10^7`直至`200`测试用例。 

直接模拟移动会产生误导，因为跳跃长度取决于每个选择的历史记录。 有用的观察是，选择类​​型只关心它被使用的次数，而不关心这些使用出现的顺序。 如果输入`j`被使用`c`次，它的贡献是一个固定的算术级数：

 适用类型`1`：```
1 + 4 + 7 + ... + (1 + 3(c - 1))
= (3c^2 - c) / 2
```适用类型`2`：```
2 + 5 + 8 + ... + (2 + 3(c - 1))
= (3c^2 + c) / 2
```适用类型`3`：```
3 + 6 + 9 + ... + 3c
= (3c^2 + 3c) / 2
```最大`K`足够大以至于`O(K^2)`或者对位置进行图形搜索是不可能的。 我们需要利用每个个体计数很小的事实。 使用单一类型`c`时间已经旅行了大约`1.5c^2`距离，所以`c`只有几千左右的时候`K`是`10^7`。 

有几种很容易被忽略的边缘情况。 第一个错误是假设最小跳跃次数也给出了路径数量。 为了`K = 5`，最小跳跃次数为`2`，但方法数的答案是`3`因为序列`(1,1)`,`(2,3)`， 和`(3,2)`所有工作。```
Input
1
5

Output
Case 1: 2 3
```另一个错误是忘记了选择类型可能未被使用。 例如，`K = 1`可以通过使用类型来达到`1`一次。 将所有三种类型视为强制会错过这种情况。```
Input
1
1

Output
Case 1: 1 1
```第三个常见错误是一组选择只计算一个排序。 如果计数是`a = 1`,`b = 1`， 和`c = 1`，相同的三个跳跃可以以六种不同的顺序出现，并且它们都是不同的方式。 

## 方法

 暴力解决方案将尝试所有可能的选择序列。 每次移动后，它都会保持每种选择类型的当前距离和当前跳跃长度。 这是正确的，因为状态包含继续该过程所需的所有信息。 然而，可能的序列数量呈指数增长。 即使只有几十步的深度也会产生太多的分支，而答案可能需要数千次跳跃。 

关键的转变是首先停止考虑跳跃的顺序。 假设类型`1`， 类型`2`，然后输入`3`被使用`a`,`b`， 和`c`次。 最终排名仅取决于这三项。 这些计数的不同序列的数量是多项式系数：```
(a + b + c)! / (a! b! c!)
```所以问题就变成了找到所有三元组`(a, b, c)`其贡献等于`K`。 

计数很小。 为了`K = 10^7`，大约只有`2600`每个计数的可能值。 枚举所有对`(a, b)`给出了大约七百万个案例。 对于每一对，我们可以计算剩余距离并检查它是否可以通过类型生成`3`在恒定的时间内。 

这给出了实用的预计算。 对于每个有效的三元组，我们更新最小跳跃次数并将其多项式贡献添加到路径数中。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 跳跃次数呈指数增长 | 搜索深度指数级增长 | 太慢了|
 | 枚举计数三元组 | O(C²) 其中 C 约为 2600 | O(K) | 已接受 |

 ## 算法演练

 1. 读取所有查询并找到所需的最大的`K`。 预计算答案仅达到此值，因为从不请求更大的位置。 
2. 计算单个跳跃类型的最大可能计数。 计数大约是`2600`，因此我们可以安全地枚举前两种类型的所有可能的用途。 
3. 对于每一个可能的对`(a, b)`，计算类型已经贡献的距离`1`和`2`。 
4.让剩余距离按类型填写`3`。 A型`3`贡献是：```
3c(c + 1) / 2
```所以我们解决：```
3c(c + 1) = 2 * remaining
```如果方程有非负整数解，我们就找到了有效的三元组。 

1. 对于每个有效的三元组，令：```
moves = a + b + c
```更新该位置的最小跳跃次数。 添加：```
moves! / (a! b! c!)
```方法的数量，因为这些选择的每个顺序都是不同的顺序。 

1. 使用预先计算的数组回答每个查询。 

为什么它有效：

 每个可能的序列都有一些最终计数`(a, b, c)`对于这三个选择。 序列行进的距离完全由这些计数决定，因此枚举通过一个三元组精确地找到每个可能的距离。 对于固定三元组，唯一剩下的自由度是选择的顺序，并且多项式系数精确地计算这些顺序。 由于每个有效的三元组都被处理，因此最小长度和序列总数都被正确计算。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

MOD = 10 ** 9 + 7

def prepare(max_k):
    cnt = 0
    while (3 * cnt * cnt + 3 * cnt) // 2 <= max_k:
        cnt += 1
    limit = cnt

    max_moves = limit * 3 + 5
    fact = [1] * (max_moves + 1)
    for i in range(1, max_moves + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (max_moves + 1)
    invfact[-1] = pow(fact[-1], MOD - 2, MOD)
    for i in range(max_moves, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    inf = 10 ** 9
    best = [inf] * (max_k + 1)
    ways = [0] * (max_k + 1)

    vals1 = []
    vals2 = []
    for i in range(limit + 1):
        vals1.append((3 * i * i - i) // 2)
        vals2.append((3 * i * i + i) // 2)

    vals3 = {}
    for i in range(limit + 1):
        vals3[(3 * i * i + 3 * i) // 2] = i

    for a, va in enumerate(vals1):
        if va > max_k:
            break
        for b, vb in enumerate(vals2):
            base = va + vb
            if base > max_k:
                break
            need = max_k - base
            c = vals3.get(need)
            if c is None:
                continue
            total = a + b + c
            add = fact[total]
            add = add * invfact[a] % MOD
            add = add * invfact[b] % MOD
            add = add * invfact[c] % MOD

            pos = base + need
            if total < best[pos]:
                best[pos] = total
                ways[pos] = add
            elif total == best[pos]:
                ways[pos] = (ways[pos] + add) % MOD

    return best, ways

def solve():
    t = int(input())
    queries = []
    mx = 0
    for _ in range(t):
        k = int(input())
        queries.append(k)
        mx = max(mx, k)

    best, ways = prepare(mx)

    ans = []
    for i, k in enumerate(queries, 1):
        ans.append(f"Case {i}: {best[k]} {ways[k]}")
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```预处理首先构建阶乘，因为三元组的序列计数使用多项式系数。 最大可能的移动次数只有几千，因此阶乘数组很小。 

数组`vals1`,`vals2`， 和`vals3`存储使用每种跳跃类型固定次数产生的距离。 主循环选择前两种类型的计数，并从剩余距离中导出第三种类型。 

字典查找类型`3`避免第三个嵌套循环。 如果没有它，迭代次数将大致是计数限制的立方。 字典将最后一次检查变成常数时间。 

更新步骤处理两种情况。 如果一个三元组在同一位置上使用的移动次数少于所有先前三元组的移动次数，则它将替换最小值。 如果它使用相同的移动次数，则其排序次数将添加到现有答案中。 这种区别很重要，因为最小长度和路总数是独立的输出。

 ## 边缘情况

 对于`K = 1`，唯一有效的三元组是`(a, b, c) = (1, 0, 0)`。 预处理发现一种类型使用的贡献`1`，给它一步，并精确计算一个命令。 

为了`K = 5`，算法找到两个不同的三元组。 三重`(2, 0, 0)`贡献一个排序，因为这两个动作都被强制键入`1`。 三重`(0, 1, 1)`贡献两种排序，因为两种不同的跳转类型可以交换。 这证实了计数逻辑是基于排列，而不仅仅是基于可达组合。 

对于较大的值，例如`K = 10000000`，该算法从不显式创建序列。 它仅检查少量可能的使用计数。 这些计数的二次界使预处理保持在限制范围内，同时仍然覆盖每个可能的解决方案。
