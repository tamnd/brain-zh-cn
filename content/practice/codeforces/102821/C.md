 ## 解决方案
 ## 问题理解

 给定一个固定的线性函数$f(x)=Ax+B$和值的集合$x_1,x_2,\dots,x_N$。 对于每个查询函数$g(x)=cx+d$，我们需要测量两个组合距恒等函数有多远。 

对于一个值$x_i$，查询的贡献为：$$|f(g(x_i))-x_i|+|g(f(x_i))-x_i|$$查询的答案是这些贡献对所有给定值的总和。 

输入包含多个测试用例。 每个测试用例给出了值的数量、查询函数的数量、系数$f$、值列表，然后是所有查询函数。 对于每个查询函数，我们打印相应的总和。 

主要的限制是两者$N$和$M$可以达到$10^5$。 评估每个值的每个查询的解决方案的执行效果约为$10^{10}$在最坏的情况下进行操作，无法在时间限制内完成。 我们需要对值进行一次预处理，并在对数时间内回答每个查询。 

棘手的部分是正确处理绝对值。 有些情况很容易破坏直接实现。 

如果系数为$x$变为零，则表达式为常数。 例如，如果查询给出$Ac-1=0$， 然后$$|(Ac-1)x_i+(Ad+B)|=|Ad+B|$$对于每一个$x_i$。 在这种情况下除以斜率是无效的。 

例如：```
1
3 1 2 0
1 2 3
0.5 5
```这里$Ac-1=2\cdot0.5-1=0$。 第一个表达式始终是$|5|$，所以它的贡献是$15$。 尝试通过除以零来计算转折点的解决方案失败了。 

当转折点超出所有值的范围时，会出现另一种边缘情况。 例如：```
1
4 1 1 0
1 2 3 4
1 100
```表达式变为$x_i+100$，所以答案是$101+102+103+104=410$。 只考虑数组中间周围的值的粗心实现可能会忽略所有项都具有相同的符号。 

重复的值是错误的另一个来源。 例如：```
1
5 1 1 0
2 2 2 2 2
1 -2
```表达式为$x_i-2$，所以每一项都为零，答案也为零。 前缀计算必须正确处理相等的值。 

## 方法

 直接方法很简单。 对于每个查询函数，替换每个$x_i$，计算两个成分，取绝对值，然后将它们相加。 这是正确的，因为它完全遵循定义。 然而，每次查询的成本$O(N)$, 给予$O(NM)$运营。 和$N=M=100000$，这变成了$10^{10}$评估，这远远超出了可用时间。 

关键的观察结果是，两种成分差异都是线性函数。 展开第一个给出：$$f(g(x))-x=A(cx+d)+B-x$$

$$=(Ac-1)x+(Ad+B)$$第二个给出：$$g(f(x))-x=c(Ax+B)+d-x$$

$$=(Ac-1)x+(Bc+d)$$两个表达式具有相同的斜率。 整个问题变成回答以下形式的查询：$$\sum_i |px_i+q|$$在哪里$p$和$q$每个查询都是已知的。 

如果$p\neq0$，我们可以分解出斜率的绝对值：$$\sum_i |p||x_i+\frac qp|$$让：$$t=-\frac qp$$然后：$$\sum_i |p||x_i-t|$$所以我们只需要一个返回的数据结构：$$\sum_i |x_i-t|$$对于任何实数$t$。 

对值进行排序后，位置$t$将数组分割成小于以下的值$t$和值大于$t$。 前缀和让我们可以在二分搜索后在恒定时间内计算这两个部分。 

这些方法的比较如下：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(NM) | O(1) | O(1) | 太慢了 |
 | 最佳 | O((N+M) log N) | O((N+M) log N) | O(N) | 已接受 |

 ## 算法演练

 1. 对所有值进行排序$x_i$并构建一个前缀和数组。 前缀总和允许我们立即计算任何前缀的总和，这足以计算到任何选定点的距离。 
2.对于各个查询函数$g(x)=cx+d$，计算共享斜率：$$p=Ac-1$$两个截距是：$$q_1=Ad+B$$和$$q_2=Bc+d$$1. 创建一个用于计算的辅助函数：$$S(p,q)=\sum_i |px_i+q|$$如果$p=0$，每一项都是相同的值$|q|$，所以结果很简单$N|q|$。 

否则，将表达式转换为：$$|p|\sum_i |x_i-t|$$在哪里：$$t=-q/p$$1. 计算$\sum_i|x_i-t|$, 找到第一个位置$x_i\ge t$。 假设这个位置是$k$。 左侧贡献：$$t\cdot k-\sum_{i<k}x_i$$右侧贡献：$$\sum_{i\ge k}x_i-t(N-k)$$将它们相加即可得到所需的距离总和。 

1. 查询的最终答案是：$$S(p,q_1)+S(p,q_2)$$以足够的精度打印该值。 

正确性来自于每个查询表达式都精确地简化为排序行上的距离和。 分割点$t$是唯一有标志的地方$x_i-t$变化。 它前面的所有值都贡献距左侧的距离，它后面的所有值贡献距右侧的距离。 由于前缀和包含两组的精确和，因此计算值始终是绝对值的真实和。 

## Python 解决方案```python
import sys
import bisect

input = sys.stdin.readline

def solve():
    data = sys.stdin.buffer.read().split()
    ptr = 0
    t = int(data[ptr])
    ptr += 1
    out = []

    for case in range(1, t + 1):
        n = int(data[ptr])
        m = int(data[ptr + 1])
        A = float(data[ptr + 2])
        B = float(data[ptr + 3])
        ptr += 4

        xs = [float(data[ptr + i]) for i in range(n)]
        ptr += n

        xs.sort()
        pref = [0.0]
        for x in xs:
            pref.append(pref[-1] + x)

        def dist_to_point(x):
            k = bisect.bisect_left(xs, x)
            left = x * k - pref[k]
            right = (pref[n] - pref[k]) - x * (n - k)
            return left + right

        def calc(p, q):
            if abs(p) < 1e-15:
                return n * abs(q)
            return abs(p) * dist_to_point(-q / p)

        out.append(f"Case {case}:")

        for _ in range(m):
            c = float(data[ptr])
            d = float(data[ptr + 1])
            ptr += 2

            p = A * c - 1.0
            q1 = A * d + B
            q2 = B * c + d

            ans = calc(p, q1) + calc(p, q2)
            out.append(f"{ans:.10f}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```输入以字节形式读取并一起解析，因为值的总数可能很大。 在处理任何查询之前，每个测试用例都会构建一次排序数组和前缀和。 

功能`dist_to_point`围绕转折点实施数学分割。`bisect_left`找到第一个不小于该点的元素，该点恰好是负值和非负值之间的边界$x_i-t$。 

功能`calc`单独处理特殊的零斜率情况。 这避免了被零除，也避免了数值不稳定。 对于非零斜率，它应用从线性绝对值到缩放距离和的变换。 

所有计算都使用浮点值，因为输入包含实数并且所需的误差容限为$10^{-6}$。

 ## 边缘情况

 当$Ac-1=0$，算法进入常量表达式分支。 为了：```
1
3 1 2 0
1 2 3
0.5 5
```斜率为零，因此第一项贡献$3\times5=15$。 第二个表达式也是具有自己的截距的常量，并且帮助器处理这两个表达式而不尝试计算转折点。 

当转折点位于排序值之外时，二分查找将返回数组的开头或结尾。 为了：```
1
4 1 1 0
1 2 3 4
1 100
```转折点是$-100$。 每个值都在右侧，因此距离计算变为：$$(1+100)+(2+100)+(3+100)+(4+100)=410$$前缀公式自然可以处理这个问题，因为分割的一侧包含零个元素。 

当所有值都相等时：```
1
5 1 1 0
2 2 2 2 2
1 -2
```转折点正是重复值。 二分查找找到第一个相等的位置，左右贡献都为零，结果正确报告为零。
