 ## 解决方案
 ## 问题理解

 这家商店有多种商品。 第 i 种以每天 x_i 件的固定价格出售。 货架的总容量为V，我们必须决定为每种商品保留多少空间v_i。 分配的容量总计必须为 V。 

每当商品库存达到零时，就会重新填充到指定的最大数量。 如果商品每天的需求量为 x_i，货架容量为 v_i，则每天需要 x_i / v_i 补充。 目标是选择所有 v_i 值，以便所有商品的补充总数尽可能小。 

输入包含多个测试用例。 每个测试用例给出了商品数量、货架总体积以及每种商品的每日销量。 输出是重新填充计数的最小可能总和。 

约束足够大，足以排除模拟或搜索可能的货架分配。 当 N 达到 100000 时，即使是 O(N^2) 方法，在最坏的情况下也需要大约 10^10 次运算，这远远超出了典型竞赛时间限制所允许的范围。 该解决方案只需处理每种商品恒定的次数，从而形成 O(N) 方法。 

主要的边缘情况来自优化的数学本质。 一个常见的错误是平均分配货架空间，因为总容量是固定的。 当产品具有不同的销售率时，这种方法就会失败。 

例如：```
Input
1
2 10
1 9
```最优输出为：```
Case 1: 4.000000
```为两种商品提供 5 个单位的空间会导致重新填充计数 1/5 + 9/5 = 2，但这不是最小值。 销售较快的产品需要更多的空间。 最佳分配使产能与销售率的平方根成正比，从而产生较低的总量。 

另一个边缘情况是所有商品具有相同的销售率。```
Input
1
3 9
4 4 4
```输出是：```
Case 1: 16.000000
```粗心的解决方案可能会尝试优先考虑某些商品，但相同的需求意味着每种商品都应该拥有相同的货架空间。 

最终的边界情况是单一产品。```
Input
1
1 7
10
```输出是：```
Case 1: 1.428571
```整个货架都属于该产品，因此答案只是 10 / 7。任何假设多个商品之间相互作用的方法在这里都会失败。 

## 方法

 一种简单的方法是尝试不同的货架空间分布并计算补充成本。 对于固定分配，成本计算很容易，因为它只是 x_i / v_i 的总和。 困难在于在无限多个可能的实值分布中找到最佳分配。 即使将我们限制在整数容量也会产生巨大的搜索空间，因为 V 可以达到 10^9。 

暴力破解的想法失败了，因为变量是连续的。 没有实用的方法来枚举所有可能的货架分配。 最坏的情况是为每种产品考虑多种可能的选择，从而导致搜索空间呈指数级增长。 

有用的观察是目标函数具有特殊的数学结构。 我们最小化项 x_i / v_i 的总和，同时保持所有 v_i 的总和固定。 这是一个凸优化问题，因此可以通过平衡增加更多货架空间的边际效益来找到最优值。 

如果一种产品的销售率较高，则为其提供更多的货架空间可以更显着地减少其补充数量。 当每种产品所获得的空间与其需求的平方根成正比时，就会出现正确的平衡。 这可以使用拉格朗日乘数导出。 

让：```
minimize Σ(x_i / v_i)

subject to:

Σv_i = V
```对于拉格朗日：```
L = Σ(x_i / v_i) + λ(Σv_i - V)
```对 v_i 求导可得：```
-x_i / v_i² + λ = 0
```所以：```
v_i² = x_i / λ
```和：```
v_i = sqrt(x_i) / sqrt(λ)
```所有容量共享相同的比例因子。 使用所有容量加起来为 V 的条件：```
Σv_i = V
```我们得到：```
sqrt(λ) = Σsqrt(x_i) / V
```将其代入目标可得出：```
answer = (Σsqrt(x_i))² / V
```整个优化消失在对输入的一次传递中。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数或更糟 | O(N) | 太慢了|
 | 最佳| O(N) | O(1) 额外空间 | 已接受 |

 ## 算法演练

 1. 读取所有商品的销售额并计算其平方根之和。 

最终的公式仅取决于这个总和，因此我们不需要存储各个容量或执行任何搜索。 
2. 对平方根之和进行平方。 

优化证明表明，最小补充次数的分子正是这个平方值。 
3. 将平方值除以货架总体积 V。 

这给出了每天可能的最小补充次数。 
4. 以足够的小数精度打印答案。 

这些值涉及平方根，因此需要浮点运算。 

为什么它有效：

 最佳分配为每个产品提供与 sqrt(x_i) 成比例的容量。 这是唯一一种增加一种产品的货架空间而减少另一种产品却无法提高总补充数量的分配。 导数条件迫使所有产品具有相同的边际改进，这是最优值的定义属性。 由于导出的分配满足容量约束，并且凸目标只有一个最小值，因此保证结果值是最优的。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for case in range(1, t + 1):
        n, V = map(int, input().split())
        x = list(map(int, input().split()))

        s = 0.0
        for value in x:
            s += math.sqrt(value)

        result = s * s / V
        ans.append(f"Case {case}: {result:.6f}")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```程序独立读取每个测试用例并立即处理它。 变量`s`存储数学公式的平方根之和，避免不必要的货架分配存储。 

表达式`s * s / V`直接计算最小补充计数。 Python 浮点数就足够了，因为所需的误差容限远大于浮点精度。 

没有索引操作或迭代搜索，因此不存在数组位置的边界问题。 除法使用浮点运算，因为结果通常不是整数。

 ## 边缘情况

 对于单个产品，该算法将平方根和计算为 sqrt(x_1)。 平方得到 x_1，除以 V 得到 x_1 / V，这正是唯一可能的再填充率，因为所有货架空间都属于该产品。 

对于同等产品，例如：```
1
3 9
4 4 4
```平方根和为 6。该公式给出 36 / 9 = 4？ 等等，前面的示例输出应该重新计算。 由于每个产品获得 3 个单位的空间，因此填充总数为 4/3 + 4/3 + 4/3 = 4。正确的输出为：```
Case 1: 4.000000
```该算法保持相等，因为所有平方根都相同。 

对于不平等的产品：```
1
2 10
1 9
```平方根和为 1 + 3 = 4。最终答案为 16 / 10 = 1.600000。 最佳容量为 2.5 和 7.5，填充次数为 0.4 和 1.2。 这证实了销售较快的产品获得了更多的货架空间，并防止了均分错误。
