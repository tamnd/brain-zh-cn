 ## 解决方案
 ## 问题理解

 我们有一群会反复玩游戏的朋友。 每轮游戏只有一个人作为监督者，其余的人$n-1$人们以玩家的身份参与。 

对于每个人$i$，我们被告知他们想作为玩家参加多少轮。 由于当一个人成为主管时，他就被排除在一轮之外，因此总轮数决定了每个人能够玩的次数。 

如果总轮数为$R$，那么人$i$将成为一名球员$R - x_i$轮次，其中$x_i$是他们被选为主管的次数。 由于每一轮只有一名监督者，因此所有监督者的总和$x_i$等于$R$。 

任务是确定最小可能的$R$这样我们就可以在各轮比赛中分配监督员，以便每个人至少玩他们要求的次数。 

这些限制促使我们更快地找到解决方案$O(n^2)$。 和$n$最多$10^5$和值高达$10^9$，任何模拟回合或尝试所有可能性的构造都是不可能的。 我们需要一个公式，将问题简化为简单的数值检查或单调条件下的优化。 

当所有需求都非常大但平衡时，或者当一个人几乎要求一切而其他人要求很少时，就会出现一种微妙的边缘情况。 例如，如果所有$a_i = 1$，那么两轮就足够了，因为除了一个人之外，每个人都可以当一次监督者，最后一个约束自然就满足了。 在这种情况下，忽视平衡监督的天真想法会错误地高估或低估。 

另一种棘手的情况是当一个值占主导地位时。 例如，$a = [10^9, 1, 1, \dots]$。 简单地对需求求和或求平均值的天真的推理是失败的，因为监督能力分布不均匀，但每轮仍然有限。 

## 方法

 一个蛮力的想法是尝试增加$R$并检查可行性。 对于固定的$R$，我们必须决定是否可以分配$R$主管插槽之间$n$那样的人$i$最多被排除在外$R - a_i$回合。 相当于，他们最多必须是主管$R - a_i$次。 

检查给定的可行性$R$，我们计算容量$c_i = R - a_i$。 如果有的话$c_i < 0$， 那$R$是不可能的。 否则，我们必须保证supervisor槽位的总数$R$可以在不超过容量的情况下进行分配。 关键条件变为$\sum \min(c_i, R)\ge R$，但存在一个更简单的观察：由于每一轮都需要一个监督者，所以我们需要分配$R$有上限的人之间的相同任务$c_i$。 

这变成了标准的可行性检查：容量总和必须至少为$R$。 这给出了$\sum (R - a_i) \ge R$，它直接简化为封闭形式条件。 

暴力破解结束了$R$会花费$O(n \cdot \max a_i)$，这太大了$a_i$最多$10^9$。 

关键的观察是可行性是单调的$R$。 如果有一些$R$作品，任何更大的$R$也有效，因为增加轮次只会增加监督能力。 这意味着我们可以进行二分搜索，但代数表明我们根本不需要搜索。 

开始于：$$\sum (R - a_i) \ge R$$我们扩展：$$nR - \sum a_i \ge R$$

$$(n-1)R \ge \sum a_i$$所以：$$R \ge \frac{\sum a_i}{n-1}$$因此答案是最小的整数$R$满足这个不等式。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | R 上的暴力破解 |$O(n \cdot \max a_i)$|$O(1)$| 太慢了 |
 | 代数约简 |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 计算总和$S = \sum a_i$。 这捕获了所有玩家集体坚持参与的总次数。 
2. 观察每一轮将总“所需参与差距”减少了$n-1$，因为每次都会排除一个人。 这将调度问题转化为线性资源平衡。 
3. 导出条件$(n-1)R \ge S$，这意味着“创建的玩家位置”总数必须涵盖所有所需的参与。 
4. 计算最小整数$R$使用上限除法来满足这个不等式。 
5. 输出该值作为最小轮数。 

### 为什么它有效

 每轮贡献准确$n-1$参与，因为除了一名玩家外，所有玩家都参与。 超过$R$轮次，可用的总参与名额为$R(n-1)$。 每个人的要求$a_i$参与度，所以总需求为$S$。 由于参与是唯一的约束，可行性仅取决于参与名额的总供给是否满足总需求。 只要总容量足够，任何主管的分配都会自动产生有效的每人分配，因为除了每轮的排除之外，没有任何人的上限限制灵活性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    s = sum(arr)
    # minimal R such that (n-1)*R >= s
    r = (s + n - 2) // (n - 1)
    print(r)

if __name__ == "__main__":
    solve()
```该实现是导出的不等式的直接转换。 唯一的微妙之处是整数上限除法，实现为$(S + n - 2) // (n - 1)$，这避免了浮点错误。 

由于任意精度整数，求和计算在 Python 中是安全的。 不需要模拟，也不需要跟踪个别主管的分配。

 ## 边缘情况

 当所有值都很小时，例如$n=3, a=[1,1,1]$，公式给出$R = 1$。 随着时间的推移，一轮已经为每个人池提供了两个参与名额，任何单轮分配都可以。 

当一种价值观占主导地位时，例如$a=[100,1,1,1]$，我们得到$S=103$,$n=4$， 所以$R = \lceil 103/3 \rceil = 35$。 每轮贡献 3 个参与槽位，35 轮产生 105 个槽位，足以满足大量需求，同时将监督约束分配给较轻的参与者。 

当所有值相等时，解决方案可以平滑扩展，因为需求和容量都线性增长，并且上限除法处理不可分性，无需特殊情况。
