 ## 解决方案
 ## 问题理解

 我们得到一行单元格，每个单元格包含一个值 0、1 或 2。每个单元格一开始都未绘制，目标是绘制所有单元格。 

我们被允许以两种不同的方式花费硬币。 第一种是直接绘画：我们可以选择任何未绘画的单元格，对其进行绘画，并支付一枚硬币。 第二个是传播操作：如果我们已经有一个值为 1 或 2 的绘制单元，我们可以用它来“感染”相邻的未绘制单元，免费绘制该邻居，同时将原始绘制单元的值减一。 值为 0 的单元格不能用于进一步传播。 

关键的张力在于，较高的价值就像有限的“能源”一样，可以将油漆传播给邻居，从而可能节省硬币。 该问题要求最终绘制整个阵列所需的最小硬币数量。 

高达 200,000 的约束 n 强制任何解都是线性或接近线性的。 任何涉及尝试起始点子集、O(n^2) 的区间 DP 或简单地模拟所有传播选择的操作都会失败。 该结构表明每个单元格的值只能使用少量次，并且传播是局部的，因此解决方案应简化为贪婪或基于扫描的计算。 

一种微妙的故障模式来自于高估传播功率。 例如，在`[2,0,0]`，人们很容易认为单个 2 可以覆盖两个邻居，但方向很重要：传播是连续的并且消耗价值，因此排序决定可行性。 另一个失败案例是将所有非零单元视为可互换的源，忽略 1 只能帮助一次，而 2 可以帮助两次。 

## 方法

 思考这个过程的一种蛮力方法是决定哪些单元最初是用硬币支付的。 有些单元格一旦被涂漆，只要还有剩余价值，它们就可以向外扩展。 人们可以尝试初始硬币涂料的每个子集并模拟传播。 这在原则上是正确的，因为每个有效的过程都以某些付费起点集开始，但子集的数量以 n 为指数，这使得 n 达到 200,000 时这是不可能的。 

关键的观察结果是，传播总是沿着邻接传播，并以线性、一次一步的方式消耗价值。 这使得该过程的行为就像从“源”构建覆盖片段。 我们可以从左到右扫描并贪婪地决定何时被迫付费，而不是选择任意的初始来源。 

关键的见解是，每当我们遇到左侧剩余传播能力无法到达的位置时，我们必须在那里开始一个新的付费段。 然后，每个付费单元格向右提供与其值相等的有限范围，并且我们维护当前范围延伸的距离。 

这将问题转化为跟踪覆盖范围的移动边界并计算我们需要重置该边界的次数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解初始绘制集+模拟| O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |

 ## 算法演练

 我们维护一个变量，表示我们仍然可以使用已激活的值免费绘制向右多远的距离。 我们还保持当前正在扫描的位置。 

1. 初始化变量`reach = 0`，这意味着我们目前无法将绘画延伸到起点之外，并且有一个计数器`coins = 0`。 
2. 从左到右遍历数组。 在每个索引处`i`，检查是否`i`在当前可达范围内`reach`。 
3.如果`i <= reach`，这个位置已经可以通过早期付费或传播的单元免费绘制，所以我们什么也不做。 
4. 如果`i > reach`，我们处于任何先前传播都无法到达的位置。 我们必须支付一枚硬币才能直接绘制这个单元格。 付费后，这个细胞就成为新的繁殖源，所以我们增加`coins`1.
 5. 一旦我们在位置付款`i`，我们设置`reach = i + a[i]`。 这反映出从这个新激活的单元格中，我们可以将绘画扩展到`a[i]`向右迈出一步。 
6. 继续直到数组末尾。 

关键的想法是我们永远不会重新审视之前的决定。 每当我们超出当前的范围时，我们就被迫创建一个新的源，并且该源将其全部可用容量贡献给未来的位置。 

### 为什么它有效

 该算法保持不变式`reach`是使用所有先前选择的付费单元及其剩余传播功率无需支付额外硬币即可绘制的最远索引。 每当我们遇到超出此边界的索引时，之前的传播步骤序列都无法到达它，因为传播一次仅移动一步，并且仅源自已绘制的正值单元格。 因此，如果此时不付款，则无法绘制该位置，因此需要新的付费来源。 选择精确支付第一个无法达到的指数是最优的，因为任何后续的选择都会使当前位置保持未绘制状态，同时不会提供任何优势，而任何早期的选择要么已经触手可及，要么不会改善对早期差距的覆盖。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    reach = 0
    coins = 0

    for i in range(n):
        if i > reach:
            coins += 1
            reach = i + a[i]
        else:
            reach = max(reach, i + a[i])

    print(coins)

if __name__ == "__main__":
    solve()
```该解决方案从左到右扫描一次，维护最远可达索引。 当位置超出该范围时，它会强制购买硬币并根据该位置的价值重置范围。 否则，如果当前单元格提供进一步的扩展，它只会更新到达范围。 

微妙的一点是更新`reach = max(reach, i + a[i])`即使没有花硬币。 这捕获了已经可达的位置仍然贡献传播功率并且可以进一步扩展覆盖范围。

 ## 边缘情况

 关键的边缘情况是第一个元素为零时。 在输入中像`[0, 2, 0]`，算法从索引 0 开始，发现它无法通过`reach = 0`，并被迫立即付款。 之后，范围可能会跳得足够远以覆盖后面的小区。 在索引 0 处支付的贪婪选择是不可避免的，因为没有先验传播源。 

另一种边缘情况是高值元素出现在长零前缀之后。 为了`[0, 0, 0, 2, 0]`，算法在索引 0、1、2 处支付，然后最终使用索引 3 来扩展覆盖范围。 每个零都会迫使一个单独的硬币，因为如果没有活动源，任何传播都无法穿过它们。 

第三种情况是多个小值重叠时。 在`[1, 0, 1, 0, 1]`，每个 1 仅稍微扩展了范围，并且该算法确保尽可能重用早期的激活。 扫描保证我们不会为已经覆盖的区域支付两次费用，并且每个新硬币都准确对应于以前无法到达的索引。
