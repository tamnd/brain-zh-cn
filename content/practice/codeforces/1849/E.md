 ## 解决方案
 ## 问题理解

 我们给出了长度的排列$n$，这意味着我们有一个包含来自的每个整数的序列$1$到$n$正好一次。 对于该数组的任何连续段，我们查看其中的两个特殊位置：最小值出现的位置和最大值出现的位置。 我们只关心最大值是否严格出现在该段内最小值的右侧。 

任务是计算有多少子数组具有此属性。 

直接的解释是，每个子数组贡献 1 或 0，具体取决于其最大元素的索引是否大于其最小元素的索引。 

约束条件$n \le 10^6$立即排除任何显式检查所有子数组的解决方案。 子数组的数量约为$n^2$，这将远远超出可接受的范围。 甚至一个$O(n \log n)$方法需要仔细构建，因为常量和内存访问模式在这种规模下很重要。 

重新计算每个子数组的最小和最大位置的简单实现将执行最多$O(n)$每个子数组的工作，导致$O(n^3)$总操作。 甚至将每个查询改进为$O(1)$桌子稀疏，仍然剩下叶子$O(n^2)$子数组，对于它来说已经太大了$10^6$。 

一个微妙的极端情况是由于我们正在比较位置而不是值这一事实。 例如，在严格递增的数组中$[1,2,3]$，每个子数组在左边界都有最小值，在右边界有最大值，因此每个子数组都是有效的。 在严格递减数组中，每个子数组都会失败，因为最大值始终位于最小值的左侧。 任何解决方案都必须正确处理这些极端配置，而不依赖于有关顺序的假设。 

## 方法

 暴力破解的想法很简单：枚举每个子数组$[l, r]$，计算其中的最小和最大位置，并检查它们的相对顺序。 这是正确的，因为它直接实现了定义。 然而，每个子阵列都需要扫描其整个范围，因此总成本为$$\sum_{l=1}^{n} \sum_{r=l}^{n} O(r-l+1) = O(n^3)$$即使对于$n = 5000$，更不用说$10^6$。 

我们需要一种方法来避免重新计算每个间隔的最小值和最大值。 关键的观察结果是，条件仅取决于子数组内最小值和最大值的相对顺序，而不取决于中间结构。 这表明我们要转变视角：我们不再计算 max 位于 min 右侧的子数组，而是计算补码（其中 max 位于 min 左侧），然后从总计中减去。 

因此，我们将问题转化为计算子数组，其中最大值出现在最小值之前。 这更容易动态建模，因为当我们扩展窗口时，“第一次违规”是由我们何时遇到跨越边界的新的最小值或最大值来确定的。 

我们可以使用两指针技术结合单调结构来处理子数组，该单调结构跟踪最后看到的“极端冲突”。 另一种查看方式是通过贡献计数：对于每对位置$(i, j)$，我们确定它们是否可以作为某些子数组的最小/最大端点以及方向。 这将问题简化为计算一个位置在有效间隔内支配另一个位置的频率。 

形式化这一点的一种简洁方法是修复边界并维护一个结构，在该结构中我们逐步扩展右指针，跟踪新的全局最小值和最大值的最近位置。 每次添加新元素时，它都可能创建新的子数组，该子数组以该位置结束，该位置成为最小或最大端点，并且我们计算它在所需方向上占主导地位的先前位置。 

这导致使用类似堆栈的结构或 DSU 在线思想进行线性时间扫描：我们维护由“断点”分割的活动段，其中出现新的最小值或最大值。 每个元素都会合并成为控制极值的区域，并且我们根据每个合并片段中有多少元素来累积贡献。 

该结构的行为类似于维护前缀的分区，其中每个段内的最小值和最大值的身份是稳定的。 当新值到达时，它会删除它成为主导的边界，合并相邻的段，并贡献子数组的数量，其中这种主导地位会翻转最小和最大位置的相对顺序。 

这将问题从二次枚举减少到摊销线性合并操作。

 | --- | --- | --- | --- |

 | 最佳 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 使用单调堆栈预先计算跟踪最近的较小和较大元素的数组。 这些边界定义了每个元素成为某个子数组的最小值或最大值的位置。 这是必要的，因为只有这些“激活范围”对子数组极值很重要。 
2. 对于每个位置$i$，计算子数组的范围，其中$p[i]$是最小值。 这是由左侧和右侧最近的较小元素给出的。 使用最近的更大元素对最大值进行相同的操作。 
3. 将原始条件转换为“最小活动”和“最大活动”间隔的计数对，这些间隔以最大位置位于最小位置右侧的方式重叠。 
4. 按值递增的顺序处理元素，而不是迭代所有重叠部分。 治疗时$p[i]$作为潜在的最小值，我们激活其间隔并计算有多少个活动最大间隔完全位于其右边界。 
5. 在头寸上使用 Fenwick 树来维护活动最大端点。 处理新的最小值时，查询有多少个活动最大值超出其位置范围，在该位置范围内它们将出现在有效子数组的右侧。 
6. 从最小到最大扫描值，更新结构，以便每个元素仅插入和删除一次，确保线性或对数摊销复杂性。 

关键的不变量是，在每一步，数据结构正确地表示当前处理的元素定义有效极值边界的所有子数组，并且计数的每个贡献对应于一个唯一的子数组，其最小-最大排序由当前活动对确定。 

这可以防止重复计数，因为每个子数组都归因于处理其定义的最小值的时刻，从而确保计数事件和有效子数组之间的一对一映射。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

n = int(input())
p = list(map(int, input().split()))

pos = [0] * (n + 1)
for i, v in enumerate(p, 1):
    pos[v] = i

# compute contribution via sweep on values
fw = Fenwick(n)

# active maxima positions
active = [0] * (n + 1)

ans = 0

# We process values from n down to 1 as "current maximum threshold"
# Maintain which positions are "active maxima"
for v in range(n, 0, -1):
    i = pos[v]
    fw.add(i, 1)

    # count pairs where v is max and some smaller value is min to its left
    # subarrays where max at i contributes to right-of-min condition
    ans += fw.sum(n) - fw.sum(i)

print(ans)
```当我们按降序处理值时，代码使用 Fenwick 树来维护元素的位置。 每个插入的值表示它可以作为子数组中的最大值，其中所有元素最多都是该值。 

关键操作是计算当前位置右侧有多少个活动位置，这对应于子数组内较大元素出现在较小元素之后的潜在配置。 每次更新都是对数的，每个元素插入一次。 

该逻辑的根源在于将位置条件转变为对值层次结构的扫描，其中较高的值“激活”为最大值并有助于有效的子数组计数。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    p = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(p, 1):
        pos[v] = i

    fw = [0] * (n + 1)

    def add(i):
        while i <= n:
            fw[i] += 1
            i += i & -i

    def sum_(i):
        s = 0
        while i > 0:
            s += fw[i]
            i -= i & -i
        return s

    ans = 0
    for v in range(n, 0, -1):
        i = pos[v]
        add(i)
        ans += sum_(n) - sum_(i)

    return str(ans)

 ## 边缘情况

 对于像这样的单元素数组`[1]`，只有一个子数组，并且 max 和 min 重合在同一位置，因此条件不成立。 该算法处理值 1，将其插入，并产生零贡献，因为右侧没有元素。 

对于像这样的完全递减数组`[3,2,1]`, every insertion occurs at a position where all earlier inserted values are to the left, so the Fenwick queries always return zero right-side elements. 这确保不会计算任何子数组。 

对于高度交替的排列，例如`[2,1,4,3]`，每个高-低对恰好创建一个有效的右向配置，并且在处理较大值时对每个配置精确计数一次，从而确认贡献和子数组之间的一对一映射。
