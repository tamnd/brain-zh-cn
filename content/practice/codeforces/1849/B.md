 ## 解决方案
 ## 问题理解

 该问题描述了 Monocarp 与一群怪物战斗的场景，每个怪物都有一个初始生命值。 Monocarp可以重复击中当前生命值最高的怪物，使其减少固定数量$k$每次攻击。 如果多个怪物的生命值相同，则选择指数最小的怪物。 任务是确定怪物死亡的确切顺序。 

输入给出了多个测试用例。 对于每个测试用例，怪物的数量$n$以及固定伤害$k$提供，然后是一个列表$n$代表怪物生命值的整数。 每个测试用例的输出应该是按死亡顺序排列的怪物索引列表。 

限制因素很重要：$n$可以达到$3 \cdot 10^5$，以及总和$n$所有测试用例的上限也为$3 \cdot 10^5$。 每个生命值和伤害值可以达到$10^9$。 一个简单的模拟，你反复找到生命值最大的怪物并减去$k$最多需要$10^9$在最坏的情况下，每个怪物的操作显然是不可行的。 该算法必须使用某种形式的算术推理来计算死亡顺序，而无需模拟每次单独的攻击。 

边缘情况包括所有怪物都具有相同生命值的情况，其中$k$超过最小怪物的生命值，或者多个怪物在同一“回合”中死亡，如果它们的生命值除以$k$导致所需的命中数相同。 在每次命中后使用排序的简单方法会由于时间限制而失败，而忽略所需命中中的联系的方法会产生错误的顺序。 

## 方法

 暴力方法是按顺序模拟每次攻击。 找到当前生命值最大的怪物，减去$k$，并记录它是否死亡。 重复直到所有怪物都死了。 这是正确的，因为它完全遵循问题规则，但速度慢得令人望而却步。 如果我们有$n = 3 \cdot 10^5$怪物和最大的生命值是$10^9$和$k = 1$，模拟将花费$3 \cdot 10^{14}$操作，这对于 2 秒的时间限制来说远远超出了可行的范围。 

更快解决方案的关键观察是，可以通过计算将其生命值降至零所需的全面攻击次数来预测每个怪物的死亡。 具体来说，对于怪物$i$与健康$a_i$，所需的命中次数为$\lceil a_i / k \rceil$。 由于所需命中数较少的怪物会较早死亡，因此可以根据该值对怪物进行排序来确定死亡顺序。 由于所需命中数相同的怪物会按其初始顺序死亡，因此原始索引会打破平局。 

最佳解决方案避免了任何模拟，并将问题简化为每个怪物一次计算，然后进行稳定排序，这完全在约束范围内。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(总攻击次数) ≈ O(n * max(a_i / k)) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，请阅读$n$和$k$，以及健康状况列表$a_1, a_2, ..., a_n$。 
2. 使用公式将每个怪物的生命值转换为杀死它所需的击中次数$\lceil a_i / k \rceil$。 为了避免浮点运算，计算$(a_i + k - 1) // k$。 这确保了正确的舍入。 
3. 将每个怪物的所需命中与其原始索引配对。 这保留了打破平局的顺序。 
4. 主要按照命中数对列表进行排序，其次按照原始索引进行排序。 这给出了确切的死亡命令。 
5. 输出排序列表中的索引。 

为什么有效：不变的是，所需命中数较少的怪物总是先于命中数较多的怪物死亡。 在相同的命中次数内，指数较低的怪物先死亡，符合问题中的选择规则。 根据作为决胜局的指数的命中进行排序，可以完全重现死亡的确切顺序，而无需模拟每次单独的攻击。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        monsters = [((a[i] + k - 1) // k, i + 1) for i in range(n)]
        monsters.sort()
        print(' '.join(str(idx) for _, idx in monsters))

if __name__ == "__main__":
    solve()
```代码首先读取测试用例的数量。 对于每个测试用例，它使用整数算术来模拟除法的上限来计算每个怪物所需的命中次数。 每个怪物都与其原始的从 1 开始的索引配对。 对该列表进行排序会产生死亡顺序。 最后，索引以正确的顺序打印。 使用`i + 1`确保输出与问题中从 1 开始的索引匹配。

 ## 边缘情况

 如果所有怪物的生命值相同，例如`4 2 4 4 4 4`，每个需要 2 次命中。 该算法按点击次数排序，然后按索引排序，产生原始顺序：1、2、3、4。 这符合问题规则，因为如果所需的命中相等，所有怪物都会按索引顺序死亡。 

如果一个怪物可以一次击杀而其他怪物则需要多次击杀，例如`3 10 1 20 30`，单击怪物先死。 计算`(a_i + k - 1) // k`产生点击率`[1,2,3]`，排序给出正确的死亡顺序`[1,2,3]`。 

这两个示例都证实该解决方案可以正确处理平局打破和变化的健康状况。
