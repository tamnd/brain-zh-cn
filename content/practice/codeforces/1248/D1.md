 ## 解决方案
 ## 问题理解

 我们得到一个仅由左括号和右括号组成的字符串。 将其视为一个循环序列，我们可以以任何方式旋转它。 

对于字符串的任何固定排列，我们可以进行每次循环旋转并检查该旋转是否形成正确的括号序列。 正确的序列可以被解释为通常意义上的正确嵌套和平衡的括号。 

字符串的“美感”被定义为它的循环旋转中有多少是有效的括号序列。 我们的操作非常具体：我们可以选择字符串中的任意两个位置，将它们的字符恰好交换一次，然后我们评估结果字符串的美观程度。 我们的目标是最大化这种美感，并输出可实现的最佳价值和实现该价值的交换。 

约束 n ≤ 500 完全改变了问题的性质。 n 的三次解已经接近极限，但在优化的 Python 中仍然合理，而交换选择上的任何指数都是不可能的。 由于存在 O(n²) 次交换，并且每次交换都会影响全局属性，因此我们被推向 O(n²) 或 O(n² log n) 式解决方案，或者精心实施的 O(n³) 解决方案。 

当字符串总体不平衡时，就会出现一个微妙的问题。 如果左括号和右括号的数量不相等，则任何旋转都不可能是正确的，因此无论交换如何，答案始终为零。 另一个重要的极端情况是交换是冗余的，例如交换相同的字符或交换不改变前缀结构的位置，这可能会误导天真的实现，假设每次交换都会改变答案。 

主要困难是循环正确性不是局部的。 交换会全局影响前缀结构，这直接决定哪些旋转变得有效。 

## 方法

 暴力方法会尝试交换每对位置，构建结果字符串，然后检查每个循环移位以计算有多少个位置是有效的。 检查一圈旋转需要使用平衡计数器的线性时间，并且有 n 圈旋转，因此评估一根字符串的成本为 O(n²)。 通过 O(n²) 次交换，总复杂度变为 O(n⁴)，这远远超出了极限。 

即使将旋转检查改进到 O(n) 仍然剩下 O(n3)，这仍然是边界，但如果我们利用括号旋转的结构属性，它就变得不必要了。 

关键的观察是我们实际上不需要模拟旋转。 关于括号序列的一个经典事实是，形成正确序列的循环移位数等于前缀平衡达到最小值的位置数。 这将问题转换为跟踪单个线性阵列的前缀最小值。 

因此，我们不考虑旋转，而是计算前缀和，其中“(”为+1，“)”为-1。 美妙之处在于该前缀和达到其全局最小值的索引数量。 

现在问题就变成了：交换两个字符后，如何最大化位置数量，实现最小前缀和？ 交换仅影响交换索引之间的段中的前缀和，因此我们可以重新计算前缀行为并计算每个候选交换的最小值。 

这将任务减少为每次交换尝试所有交换并重新计算前缀统计信息，总体时间复杂度为 O(n3)。 当 n ≤ 500 时，在严格但现实的约束下，这在 Python 中是可以接受的，特别是因为操作是简单的整数更新。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（每次交换的所有旋转）| O(n⁴) | O(n) | 太慢了|
 | 最优（交换+前缀重新计算）| O(n3) | O(n) | 已接受 |

 ## 算法演练

### 1.将字符串转换为前缀平衡形式

 我们将 '(' 映射到 +1，将 ')' 映射到 -1 并计算前缀和。 该数组完全确定哪些旋转是有效的，因为旋转对应于该前缀结构中的不同起点。 

该前缀数组的最小值是计算有效循环移位的基线。 

### 2. 计算基线美感

 我们计算有多少个索引达到全局最小前缀和。 这给出了没有任何交换的初始答案。 

这是所有未来互换的下限。 

### 3. 尝试所有交换（包括无操作交换）

 对于每一对 (i, j)，我们交换字符并从头开始重新计算前缀数组。 

我们不尝试增量调整，因为前缀结构是全局的，并且在 n ≤ 500 时重新计算更简单、更可靠。 

### 4. 交换后重新计算前缀和

 应用交换后，我们以 O(n) 的时间重建余额数组。 此步骤至关重要，因为即使是很小的更改也可能会改变最小值并在发生位置重新分配。 

### 5. 计算交换字符串的美观度

 我们扫描新的前缀数组，找到它的最小值，并计算它出现的次数。 

这个计数是这次交换的美妙之处。 

### 6. 跟踪最佳交换

 我们保留找到的最大美丽值并存储相应的索引。 

如果多次交换得到相同的结果，则任何一次交换都是有效的。 

### 为什么它有效

 正确性取决于循环有效旋转与全局最小前缀和的位置之间的等价性。 这将圆形结构条件简化为线性极值条件。 由于交换仅排列两个字符，因此它仅在本地修改前缀和，但可以移动全局最小分布。 详尽的测试交换保证我们探索所有可能的方法来重塑这个最小的景观，因此永远不会错过最佳的配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def compute_beauty(s):
    n = len(s)
    bal = 0
    pref = []
    for ch in s:
        if ch == '(':
            bal += 1
        else:
            bal -= 1
        pref.append(bal)

    mn = min(pref)
    cnt = sum(1 for x in pref if x == mn)
    return cnt

def solve():
    n = int(input().strip())
    s = list(input().strip())

    best_val = -1
    best_i, best_j = 1, 1

    for i in range(n):
        for j in range(i, n):
            if i == j:
                cur = compute_beauty(s)
            else:
                s[i], s[j] = s[j], s[i]
                cur = compute_beauty(s)
                s[i], s[j] = s[j], s[i]

            if cur > best_val:
                best_val = cur
                best_i, best_j = i + 1, j + 1

    print(best_val)
    print(best_i, best_j)

if __name__ == "__main__":
    solve()
```该解决方案将美丽计算分离到一个辅助函数中，该函数从头开始重建前缀余额。 这可以避免增量更新中的细微错误，当交换影响广泛的后缀时，这些错误很容易出错。 

双循环会在 O(n²) 中尝试每次交换，并且每次评估都会在 O(n) 中重新计算前缀和。 交换会立即撤消，以保持下一次迭代的正确性。 

索引仅在输出时转换为基于 1 的索引。

 ## 边缘情况

 具有所有相同括号的字符串，例如“((((”或“))))”永远不会产生积极的美感。 前缀和是单调的，因此最小值仅出现在一个端点。 任何交换都会保留这种结构，并且算法会正确评估相同的交换结果，而无需假设可以进行改进。 

单字符字符串没有有意义的循环结构。 前缀数组仅包含一个值，因此最小值很容易达到一次。 交换循环仍然运行，但仅评估无操作交换，产生稳定的结果。 

选择交换相同字符的字符串测试实现是否意外地假设交换总是改变结构。 由于交换相同的符号会使前缀数组保持不变，因此重新计算仍然必须产生相同的美感并且不会引入不一致。
