 ## 解决方案
 ## 问题理解

 我们得到一个带有加权边的无向图，其中权重称为色彩。 任务是从城市 1 到城市 n，但不只是通过任何路径。 

首先，在所有可能的路由中，我们只对边数最少的路由感兴趣，这意味着跳数而非权重方面的最短路径。 在所有这些最短的跳数路径中，我们需要一条能够最大化沿路径的最大和最小边缘色彩之间的差异的路径。 

所以这个问题本质上是一个两级优化。 第一个约束将我们固定在最短路径子图中的边数。 在该限制集中，我们想要选择一条最大化边权重定义的范围值的路径。 

约束很大，最多有 100,000 个节点和 200,000 条边。 这立即排除了枚举所有最短路径，因为密集图中的最短路径的数量可以呈指数增长。 任何尝试存储或枚举所有候选路径的解决方案都将失败。 

我们应该期望 O(n + m) 或 O(m log m) 式的解决方案，可能使用 BFS 加上额外的优化步骤。 

当存在多个最短路径时，就会出现一个微妙的问题。 一种简单的方法可能会计算最短路径树，然后尝试贪婪地调整它，但最短路径树并不是唯一的，不同的 BFS 父代选择可以极大地改变可实现的色彩范围。 

另一个陷阱是假设全局最佳色彩范围路径也是最短的。 长度稍长的路径可能具有更好的颜色范围，但它是无效的，因为最短路径约束占主导地位。 

一个幼稚思维的失败小案例：

 考虑一个图表：

 1 - 2 - 3 - 4（所有边权重为 1）

 1 - 3（边权重 100）

 1 - 4（边权重 0）

 从 1 到 4 的最短路径的长度为 2：1-3-4 或 1-2-3-4 如果更长，则不是最短的。 由于权重极端，简单的算法可能更喜欢 1-3-4，但它必须只考虑最短路径。 

因此，挑战在于如何有效地将注意力限制在最短路径上，同时仍然优化边缘权重的次要目标。 

## 方法

 我们从最直接的想法开始：从节点 1 运行 BFS 来计算边到每个节点的最短距离。 然后我们将自己限制在尊重最短路径分层的边上，这意味着我们只考虑从距离 d 处的节点到距离 d+1 处的节点的转换。 这形成了由 BFS 级别分层的有向非循环结构。 

一旦我们有了这个结构，问题就变成选择从层 0 到层 dist[n] 的路径，同时最大化沿路径的最大和最小边缘权重之间的差异。 

该 DAG 内部的一种强力方法是枚举所有路径或对跟踪迄今为止所见的最小和最大边权重的状态进行 DP。 然而，DP 状态太大：每个节点都可以通过许多可能的最小-最大组合来到达，并且在最坏的情况下，此类状态的数量可能会爆炸到 O(2^n)。 

关键的观察结果是，答案仅取决于沿路径选择一对边缘作为最小和最大色彩值。 一旦我们修复了这两个边界，我们只需要检查是否存在一条最短路径，该路径位于权重位于该区间内的边内，并且仍然以最短的长度连接 1 到 n。 

这将问题转化为经典的基于排序边权重的两指针可行性问题，并结合 BFS 可行性检查。 

我们按色彩对所有边缘进行排序。 然后，我们在可能的最小和最大边缘值上使用滑动窗口。 对于每个候选窗口 [L, R]，我们仅使用权重在此范围内的边检查是否存在从 1 到 n 的最短路径。

为了检查可行性，我们在过滤后的图上运行 BFS 并验证 distance[n] 是否等于完整图中预先计算的最短距离。 

这是可行的，因为除了删除一些边缘之外，限制边缘不会改变 BFS 层结构； 如果在限制下仍然存在最短路径，则 BFS 距离将保持相等。 

我们在排序的边权重上维护两个指针，在需要时扩展 R 并缩小 L，并跟踪最佳可行区间。 

最后，一旦找到最佳间隔，我们就使用过滤后的图中的 BFS 父指针重建实际路径。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 通过最小/最大跟踪对路径进行强力 DP | 指数| O(nm) 态 | 太慢了|
 | BFS分层+滑动窗口+可行性BFS | O(m log m + m n BFS 摊销) | O(n + m) | 已接受 |

 ## 算法演练

 1. 从完整图中的节点 1 运行 BFS，以计算到每个节点的边数的最短距离。 该距离定义了有效解决方案唯一允许的路径长度。 如果节点 n 不可到达，我们将停止，但问题是保证连接性。 
2. 将到节点 n 的最短距离存储为 target_length。 任何有效的答案都必须是恰好这个长度的路径。 
3. 按色彩值对所有边进行排序。 这使我们能够按升序推理允许权重的候选区间。 
4. 在排序的边上使用两指针滑动窗口，根据排序列表中的边索引维持当前区间[L，R]。 该间隔对应于仅允许其色彩度位于两个选定值之间的边缘。 
5. 对于每个候选区间，在图上构造一个临时 BFS，但仅使用色彩度位于 [L, R] 中的边。 在 BFS 期间，计算距节点 1 的最短距离。 
6. 如果节点 n 可达并且其距离等于 target_length，则该区间是可行的，因为它在限制边权重的同时保留了最短路径最优性。 
7. 如果可行，尝试扩大间隔以增加最大和最小色彩之间的差异。 否则，缩小或移动间隔以恢复可行性。 
8. 跟踪最大化 R_value 减去 L_value 的最佳区间，同时保持可行。 
9. 找到最佳间隔后，运行一个仅限于该间隔的最终 BFS，同时存储父指针以重建实际的最短路径。 
10. 使用父数组输出从 1 到 n 重建的路径。 

### 为什么它有效

 该算法依赖于两个嵌套的单调结构。 首先，BFS 分层确保所有有效的解决方案都必须存在于由最短距离定义的 DAG 上。 其次，固定权重区间的可行性是单调的：如果区间 [L, R] 允许最短路径，则任何较大的区间 [L', R'] 且 L' ≤ L 且 R' ≥ R 也允许它。 这种单调性使得滑动窗口能够有效地探索候选范围，而不会丢失最佳解决方案。 BFS检查保证了正确性，因为它准确地表征了边缘约束下是否存在最短长度路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(n, adj, allowed):
    dist = [10**18] * (n + 1)
    parent = [-1] * (n + 1)
    dist[1] = 0
    q = deque([1])

    while q:
        u = q.popleft()
        for v, idx in adj[u]:
            if not allowed[idx]:
                continue
            if dist[v] > dist[u] + 1:
                dist[v] = dist[u] + 1
                parent[v] = u
                q.append(v)

    return dist, parent

def solve():
    n, m = map(int, input().split())
    edges = []
    adj = [[] for _ in range(n + 1)]

    for i in range(m):
        u, v, c = map(int, input().split())
        edges.append((u, v, c))
        adj[u].append((v, i))
        adj[v].append((u, i))

    # BFS for shortest path length
    dist0 = [10**18] * (n + 1)
    q = deque([1])
    dist0[1] = 0

    while q:
        u = q.popleft()
        for v, _ in adj[u]:
            if dist0[v] > dist0[u] + 1:
                dist0[v] = dist0[u] + 1
                q.append(v)

    target = dist0[n]

    # sort edges by colorfulness
    order = sorted(range(m), key=lambda i: edges[i][2])
    colors = [edges[i][2] for i in order]

    allowed = [False] * m

    def check(l, r):
        for i in range(m):
            allowed[i] = False
        for i in range(l, r + 1):
            allowed[order[i]] = True

        dist, parent = bfs(n, adj, allowed)
        return dist[n] == target, parent

    best_l, best_r = 0, 0
    j = 0

    for i in range(m):
        while j < m:
            ok, _ = check(i, j)
            if ok:
                if colors[j] - colors[i] > colors[best_r] - colors[best_l]:
                    best_l, best_r = i, j
                j += 1
            else:
                break

    ok, parent = check(best_l, best_r)

    path = []
    cur = n
    while cur != -1:
        path.append(cur)
        cur = parent[cur]

    path.reverse()

    print(len(path) - 1)
    print(*path)

if __name__ == "__main__":
    solve()
```该解决方案首先计算从节点 1 到所有节点的最小跳距离。 这修复了唯一有效的路径长度。 然后，它按色彩对边缘进行排序，并将问题视为在这些值上选择最佳连续间隔。 

检查函数使用布尔掩码隐式重建过滤图，并运行 BFS 来验证约束下是否仍然存在最短路径。 父指针仅在最终的重建调用中存储，以避免不必要的内存开销。 

一个微妙的点是，我们必须与原始最短距离进行比较，而不是在每个过滤的 BFS 内重新计算目标长度，因为删除边缘只会增加距离。

我们按权重对边进行排序：1、5、6、10。

 ## 边缘情况

 一种重要的边缘情况是最佳间隔压缩为单个边缘权重。 在这种情况下，只允许一种颜色的边，但 BFS 仍然正确地找到最短路径（如果存在）。 该算法自然地处理这个问题，因为区间 [L, L] 是有效的，并且像其他区间一样进行检查。 

另一种情况是当存在多个具有相同跳数但完全不同的边集的最短路径时。 BFS 可行性检查确保只有那些完全包含在所选间隔中的路径才会做出贡献，因此不会发生错误的边缘混合。 即使存在较短颜色范围的路径，只有当它仍然保持最短距离的可达性时才会选择它。 

最后一个微妙的情况是删除边会断开图的连接。 在这种情况下，BFS 返回到 n 的无限距离，并且该间隔被拒绝。 这可以防止错误地接受不可行的颜色范围，从而破坏最短路径约束下的连接。
