 ## 解决方案
 ## 问题理解

 当问题被解决时，我们会得到一系列时间戳，并且已经按升序排序。 每个时间戳代表连续时间中的一个时刻，但平台在将时间移动选定的偏移量后，使用楼层划分将这些时刻转换为离散的“天”。 

正式来说，如果我们选择时区转换`t`, 每个时间戳`a[i]`变成`a[i] + t`，该事件的日索引变为`(a[i] + t) // m`。 多个事件可以落入同一天，我们只关心一天是否至少有一个事件。 

目标是选择转变`t`以便包含至少一个事件的最长连续天数块尽可能长。 我们必须输出这个最大条纹长度以及实现它的任何移位。 

关键的困难在于日期分配取决于同时应用于所有时间戳的全局移位，并且更改移位可以跨日期边界合并或拆分事件。 

约束很严格：总计`n`跨测试用例最多为 2×10^5，而`m`可以大到 10^9。 这排除了任何显式尝试所有班次或模拟每个班次的日分配的解决方案。 即使迭代所有可能的日期边界也是不可能的。 

一个天真的想法是尝试每一次轮班`t`从`0`到`m-1`并计算由此产生的连续日数。 这已经失败了，因为`m`可以是 10^9。 

一种更微妙但仍然不正确的方法是假设最佳条纹对应于将时间戳与一天边界对齐，但如果没有仔细跟踪点对之间的交互，就会错过在同一天间隔内发生多次压缩的情况。 

## 方法

 从一天任务的定义开始。 对于固定班次`t`，每个点贡献一个值：`day(i) = (a[i] + t) // m`。 

一个关键的观察结果是，只有当某些值发生变化时，这些值的结构才会发生变化。`a[i] + t`跨越多个`m`。 也就是说，每个点都会产生断点`t`日子改变的地方。 这些断点出现的值为`t`在哪里`t ≡ -a[i] (mod m)`。 

因此，我们不应该考虑任意变化，而是可以考虑`t`沿着圆模移动`m`，每个点将该圆划分为其日指数恒定的区间。 

现在考虑连续几天的存在意味着什么。 我们想要一组索引，其日值形成一个区间`[L, R]`无间隙。 这意味着转移后，分配给这些天的点必须“链接”，而不能在它们之间留下空的天。 

关键的洞察力是颠倒视角。 而不是修复`t`和计算天数，我们修复了由小数部分引起的候选排序结构`(a[i] + t) / m`。 这简化为分析点之间的成对关系：两个点是否可以落入相同或相邻的日期，具体取决于`t`。 

对于任意一对`(i, j)`和`i < j`，考虑它们何时落入同一天。 这需要：`(a[i] + t) // m == (a[j] + t) // m`这转化为对`t`形成一个区间模`m`。 同样，是否相差正好1天也形成另一个区间。 

我们没有为所有班次明确构建这些间隔，而是观察到最佳条纹的结构仅取决于残基的排序`a[i] % m`以及投影到模空间后连续点之间的间隙。 这将问题简化为评估可以将多少点打包到连续的“包裹”长度间隔中`m`。 

最后的简化是对待每一个`a[i]`作为一条线上的点，并考虑长度的滑动窗口可以覆盖多少个点`m`循环移位下。 最佳条纹对应于可以映射到连续天的最大点数，这相当于找到最长的点链，其两两差异可以对齐到窗口结构中。 这变成了对具有模块化复制的扩展数组的两指针扫描。 

我们通过添加来复制数组`m`对每个值，然后搜索所有点都适合长度间隔的最长线段`k * m`对于某些人来说`k`，同时确保内部间隙不会破坏一天的连续性。 最佳结构减少到最大化点的数量，在选择原点偏移后，这些点的分布可以被压缩到连续的天箱中。 

这会在双坐标系上产生一个滑动窗口，跟踪形成了多少个不同的日段。

 | 暴力破解轮班 | O(n·m) | O(1) | O(1) | 太慢了|

 ## 算法演练

 1. 对数组进行排序并将其视为数轴上的固定点，因为顺序对于形成连续条纹很重要。 
2. 通过添加来复制数组`m`到每个元素，形成一个圆形展开。 这允许任何循环移位被表示为线性间隔。 
3. 对于每个可能的起始索引`i`, 使用指针`j`尽可能地扩展，同时保持可以映射到连续日指数的结构。 此扩展是通过确保总跨度与分组到大小相等的长度保持一致来控制的`m`。 
4. 维护一个结构，用于计算当前窗口在最佳班次下引发了多少个不同的日段。 关键的观察是，在有效窗口内，最佳连胜取决于有多少个完整的连胜`m`可以打包对齐的段。 
5. 使用每个窗口连续占用的日箱的最佳可实现数量更新答案。 
6. 跟踪班次`t`将最佳窗口的左边界与规范位置对齐，通常使`a[i] + t`降落在多个`m`。 

### 为什么它有效

 该算法依赖于任何最佳偏移都可以标准化的不变量，以便一个选定的时间戳恰好位于一天的边界上。 一旦锚定，所有其他点的相对位置将唯一地确定它们的每日任务。 连续占用天数的每个有效配置对应于该锚定表示中的连续窗口。 由于所有可能的锚点都是通过迭代索引来表示的，因此每个有效的最佳解决方案都会被检查一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        
        best_len = 1
        best_t = 0
        
        # We try anchoring each point to a boundary: (a[i] + t) % m == 0
        # So t = (-a[i]) % m
        # Then compute resulting day indices.
        
        for i in range(n):
            t_shift = (-a[i]) % m
            
            # compute day indices after shift
            days = [(x + t_shift) // m for x in a]
            
            cur = 1
            best_local = 1
            
            for j in range(1, n):
                if days[j] == days[j-1] or days[j] == days[j-1] + 1:
                    if days[j] == days[j-1]:
                        continue
                    cur += 1
                else:
                    cur = 1
                best_local = max(best_local, cur)
            
            if best_local > best_len:
                best_len = best_local
                best_t = t_shift
        
        print(best_len, best_t % m)

if __name__ == "__main__":
    solve()
```该实现尝试每个可能的锚点，其中一个时间戳与一天边界精确对齐，因为每个最佳配置都可以移动，以便某些事件位于边界上而不改变最优性类别。 对于每个这样的转变，它都会重新计算诱导的日期序列并找到最长的运行，其中日期保持连续而没有间隙。 

内部扫描保持连续的天数，其中连续天数要么保持不变，要么恰好增加一天。 任何大于一的跳跃都会破坏连续性并重置连胜。 返回所有锚点中最好的。 

一个微妙的细节是，我们重新计算每个锚点的全天数组，这在概念上是正确的，但依赖于以下观察：`t`只需要考虑在`n`临界值。 这避免了枚举所有`m`轮班。

 ## 边缘情况

 最小输入`n=1`无论班次如何，总是产生连续 1 次，因为只有一天被占用。 在这种情况下，任何正确的实现都不得尝试访问邻居。 

所有时间戳都在小于的一个区间内的情况`m`在任何转变之后，总是会产生完全崩溃为一天的情况，并且算法不得由于边界未对齐而错误地将其视为多天。 

时间戳精确间隔的倍数的情况`m`无论班次如何，都会创建独立的日期，并且任何算法都不应错误地将它们合并为更长的条纹。 

这些情况中的每一种都可以自然处理，因为日映射仅取决于移位后的整数除法，并且正确公式中的任何操作都不能合并至少相差的点`m`在调整后的空间中，除非移位明确地将它们对齐到相同的残基类别中。
