 ## 解决方案
 ## 问题理解

 我们得到了一组独立的树。 对于每棵树，每个顶点都有两个数字，描述在有效的重建中应该有多少个两种不同颜色的入射边。 树中的每条边都必须准确分配白色或黑色两种颜色中的一种，并且这些分配必须符合每个顶点的要求。 

形式上，对于每个顶点，入射白边的数量必须与第一个给定值匹配，并且入射黑边的数量必须与第二个给定值匹配。 任务是确定树边缘的这种着色是否存在，如果存在，则构造任何有效的着色。 

输入大小足够大，任何解决方案都必须与所有测试用例的顶点总数基本呈线性。 由于 n 的总和高达 3·10^5，即使 O(n log n) 解决方案也是可以接受的，但没有必要，而每个测试用例的任何二次方都是不可能的。 

局部思考时会出现一个微妙的问题：仅顶点约束不足以保证可行性。 例如，在某些部分分配中，顶点可能需要比其度数允许的更多的白边，但这只有在考虑其邻居后才变得明显。 另一种失败模式是贪婪地为每个边分配颜色而不保持全局一致性，这很容易在稍后的遍历中违反约束。 

最小的说明性失败情况是一条包含三个顶点的路径，其中中间顶点需要两条白边，但一个端点由于其自身的约束而已经强制使用黑边。 幼稚的局部分配可能会独立分配颜色，并最终在中心不一致，即使全局解决方案可能存在也可能不存在，具体取决于确切的值。 

核心困难在于，我们正在解决树上的全局可行性问题，该树具有跨两种颜色的每个节点度划分约束。 

## 方法

 暴力方法会尝试每棵树的 n−1 条边的所有可能的着色，并检查是否满足顶点约束。 每条边都有两个选择，因此每棵树有 2^(n−1) 种可能性。 即使对于 n = 50，这也是不可行的，而对于 n 高达 3·10^5 的情况，这也是完全不可能的。 

问题的结构表明要利用底层图是树这一事实。 树允许自下而上的推理，因为删除叶子可以减少问题的大小，而不会在剩余部分之间创建循环或依赖关系。 关键的观察是，每条边仅对两个端点有贡献，因此决定其颜色可以解释为在顶点之间传递“需求”。 

如果我们对树进行生根，每个顶点都可以使用其子节点的边来决定需要满足多少条白边，同时向上传递剩余的要求。 这自然会导致自下而上的流程解释：每个子树计算它必须发送到其父级的白边数量。 

关键的见解是，对于每个节点，一旦处理了所有子节点，影响其父节点的唯一剩余边缘就是父边缘本身。 这意味着我们可以通过确保每个子树向上精确传达一个剩余自由度来强制一致性。 

这将问题转化为通过 DFS 计算边缘颜色的一致分配，其中每个子树报告它仍然需要多少个白色边缘，并且我们确保该值与父边缘选择相匹配。

 ## 算法演练

 我们以任意节点为树根，例如 1。然后，我们执行深度优先遍历，并将每个子树视为必须满足内部约束的单元，同时向上报告残差要求。

1. 在任意位置将树作为根并运行 DFS 来建立父子关系。 这一步为我们提供了在没有循环的情况下传播约束的方向。 
2. 对于每个节点 u，定义一个值 rem[u]，表示以 u 为根的子树中必须有多少条白边将 u 连接到其父节点。 最初，rem 是未知的，将自下而上计算。 
3.在DFS时，首先处理u的所有孩子v。 每个子节点返回其 rem[v]，表示从 v 到 u 必须有多少条白边。 该值立即被解释为一个决策：在聚合行为中，边缘 (u, v) 恰好是白色的 rem[v] 次，但由于边缘是一次性的，因此在一致的构造中，rem[v] 将是 0 或 1。 
4. 对于每个子边（u，v），我们通过在v处强制一致性来决定其颜色。如果v在内部子树解析后仍然需要一个白色边来满足其要求，我们将（u，v）指定为白色； 否则我们将其指定为黑色。 这相应地减少了 v 的要求。 
5. 在节点 u 处，处理完所有子节点后，我们计算 u 仍需要其父边有多少条白边。 这是从其原始 wi 减去指定为白色的子边所满足的贡献得出的。 
6. 如果 u 不是根，则将此剩余要求向上传递为 rem[u]。 如果u是根，则它必须以零残差要求结束，否则不存在解。 
7. 如果在任何时候节点的要求变为负值或超过其可用程度，我们立即得出不可能性的结论。 

微妙之处在于，树结构保证一旦处理了子树，除了到父树的单边之外，所有内部约束都已经固定，因此每个子树都减少到单个标量要求。 

### 为什么它有效

 不变的是，在处理节点 u 后，其子树内的每条边都是固定的，并且该子树中的所有顶点都满足其所需的白色和黑色事件计数，除了可能从边到 u 父级的贡献之外。 值 rem[u] 准确地表示必须在该父边上分配多少条白边才能使 u 的子树可行。 

由于每个子树仅向上传递单个标量，因此不会累积冲突的需求。 一旦更深的子树被解析，每个决策都是局部于边缘的，并且由于树没有循环，因此不会在约束冲突的情况下重新访问边缘。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        w = [0] * (n + 1)
        b = [0] * (n + 1)

        for i in range(1, n + 1):
            wi, bi = map(int, input().split())
            w[i] = wi
            b[i] = bi

        g = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        parent = [0] * (n + 1)
        order = []
        stack = [1]
        parent[1] = -1

        while stack:
            u = stack.pop()
            order.append(u)
            for v in g[u]:
                if v == parent[u]:
                    continue
                if parent[v] != 0:
                    continue
                parent[v] = u
                stack.append(v)

        children = [[] for _ in range(n + 1)]
        for v in range(2, n + 1):
            children[parent[v]].append(v)

        rem = [0] * (n + 1)
        ok = True
        edges = []

        for u in reversed(order):
            need = w[u]
            for v in children[u]:
                if rem[v] > 1:
                    ok = False
                    break
                if rem[v] == 1:
                    edges.append((u, v, 'W'))
                    need -= 1
                else:
                    edges.append((u, v, 'B'))
                need -= 0 if rem[v] == 1 else 0
            if not ok:
                break
            if need < 0 or need > 1:
                ok = False
                break
            rem[u] = need

        if not ok or rem[1] != 0:
            out.append("No")
        else:
            out.append("Yes")
            for u, v, c in edges:
                out.append(f"{u} {v} {c}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现使用迭代 DFS 构建有根树，以避免递归深度问题。 这`parent`数组建立结构，并且`children`以有根形式存储邻接关系，因此每条边都按照自下而上的顺序处理一次。 

关键状态是`rem[u]`，它编码 u 是否仍然需要其父级的白边。 在处理子项时，每个子项贡献一个白色或黑色边缘，这直接减少了 u 处的剩余需求。 根需要以零剩余需求完成，因为它没有父边缘。 

一个常见的陷阱是忘记每个边缘必须准确记录一次。 我们在从父级到子级的处理过程中存储边缘，以确保唯一性。 

## 工作示例

 考虑链 1-2-3 中的三个节点的简单树，其中顶点 2 需要一条白边，而顶点 1 和 3 需要零。 

我们以 1 为根并自下而上进行处理。 

| 节点| 儿童加工| 雷姆值 | 边缘行动 | 雷姆[u] |
 | --- | --- | --- | --- | --- |
 | 3 | 无 | w[3]=0 | w[3]=0 | 无 | 0 |
 | 2 | 3 | 雷姆[3]=0 | (2,3)=B | 1 |
 | 1 | 2 | 雷姆[2]=1 | (1,2)=W | 0 |

 这显示了如何使用到 3 的边来满足节点 2 的需求，然后向上传播。 

现在考虑根无法满足约束的情况：w=1 的单个节点。 因为它没有边缘，所以这是不可能的。 

| 节点| 儿童加工| 雷姆值 | 行动| 雷姆[u] |
 | --- | --- | --- | --- | --- |
 | 1 | 无 | w[1]=1 | w[1]=1 | 无 | 1 |

 Root必须有rem[1]=0，所以答案是不可能的。

 ## 边缘情况

 单顶点情况暴露了根必须以零剩余需求结束的要求。 该算法分配 rem[1]=w[1]，并且由于没有父边来满足它，因此任何非零值都会立即强制拒绝。 

一棵星形树的中心需要许多白色边缘但子节点不足，这表明传播失败。 由于每个叶子最多贡献一个边缘，如果中心需要比可用邻居更多的白边缘，则 rem 在处理过程中变为负值，在到达根之前触发拒绝。
