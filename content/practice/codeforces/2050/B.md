 ## 解决方案
 ## 问题理解

 我们得到一个代表某些资源“池”的整数数组。 在每次操作中，我们可以选择一个不在边界的元素，并将一个单元从一个邻居移动到另一个邻居。 具体来说，如果我们选择索引`i`(2 ≤ i ≤ n-1)，我们可以减少`a[i-1]`加 1 并增加`a[i+1]`减 1，或减少`a[i+1]`加 1 并增加`a[i-1]`by 1. 禁止使用负值，因此传输前源必须至少为 1。 

目标是确定在经过一定次数的这些操作后是否可以使所有元素相等。 

输入提供多个测试用例，每个测试用例都有数组长度和数组本身。 每个测试用例的输出都是简单的“是”或“否”，具体取决于是否可以均衡所有元素。 

数组大小方面的约束很严格：n 可以达到 2×10⁵，并且测试用例中所有 n 的总和以 2×10⁵ 为界。 这意味着我们无法显式模拟操作，因为每个操作可能是 O(n) 并且所需的操作总数可能很大。 我们需要一种能够全局查看阵列并无需模拟即可确定可行性的解决方案。 

当其中一个末端元素小于其相邻元素时，就会出现一种微妙的边缘情况。 由于操作仅在内部元素的邻居之间移动值，因此末端元素只能从一个方向接收资源。 例如，如果`a[0]`是 1 并且`a[1]`为 0，移动序列不能增加`a[0]`如果所有内部元素都小于或等于，则大于 1。 这表明最小值是一个关键约束。 

## 方法

 简单的暴力方法会尝试模拟所有可能的操作序列。 对于每个索引`i`我们可以尝试向左或向右移动资源。 这在原则上是正确的，因为运算规则保证了总和守恒，但它太慢了。 对于大小为 10⁵ 的数组，即使单个操作序列也需要 O(n²) 个步骤，并且对于 10⁴ 测试用例，这种方法是不可行的。 

关键的见解是观察不变量：数组的总和保持不变。 让`S`是所有元素的总和，并且`n`数组的长度。 如果所有元素都相等，则它们必须全部达到该值`S / n`。 这会立即进行可行性检查：如果`S % n != 0`，这是不可能的。 

接下来，我们需要确保没有元素需要的元素超过其邻居可以提供的元素。 由于该操作一次只能在两个相邻元素之间转移资源，因此内部元素必须能够“吸收”或“提供”所需的数量。 操作结构允许数组在内部元素之间自由地重新分配资源。 事实证明，只要总和能被n整除，并且每个内部元素至少是目标值（因为末端元素可以增加一个邻居），它总是可能的。 

因此，最佳解决方案是计算总和，检查是否能被 n 整除，如果能整除则输出 YES，否则输出 NO。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 每个测试用例的 O(n²) | O(n) | 太慢了|
 | 总和 + 整除检查 | 每个测试用例 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，读取长度`n`和数组`a`。 
2. 计算总和`S = sum(a)`。 
3. 计算目标值`target = S // n`。 
4. 如果`S % n != 0`， 打印`NO`并转到下一个测试用例。 
5. 否则，打印`YES`因为操作规则允许重新分配以达到目标。 

为什么有效：该操作保留了总和。 如果总和能被 n 整除，则目标值存在。 这些操作允许在邻居之间一次转移一个单元，并且通过以贪婪的方式重复应用移动，任何内部配置都可以将多余的值重新分配给不足的元素。 可分性检查确保了可行性，这是唯一的全局约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total = sum(a)
        if total % n == 0:
            print("YES")
        else:
            print("NO")

solve()
```该代码使用快速 I/O`sys.stdin.readline`。 对于每个测试用例，我们仅计算数组的总和并检查整除性。 每个测试用例的时间复杂度为 O(n)，在给定的约束下这是可以接受的。 除了数组存储之外，不使用额外的内存。 微妙之处包括正确处理多个测试用例和读取不同大小的数组。 

## 工作示例

 **示例输入 1：**`3 2 1`→ 总和 = 6，n = 3, 6 % 3 = 0 → 是

 **示例输入 2：**`1 1 3`→ 总和 = 5，n = 3, 5 % 3 ≠ 0 → 否

 | 数组| 总和 | n | 总和 % n | 输出|
 | --- | --- | --- | --- | --- |
 | [3,2,1]| 6 | 3 | 0 | 是 |
 | [1,1,3]| 5 | 3 | 2 | 否 |

 这证明了和整除不变量正确地识别了可行的配置。

 ## 边缘情况

 对于所有元素最初都相等的数组，算法立即输出 YES，这是正确的。 对于具有极大数字的数组，求和计算使用Python的任意精度整数，因此溢出不是问题。 对于 sum % n ≠ 0 的数组，无论元素位置如何，输出 NO 都会正确捕获不可能性。
