 ## 解决方案
 ## 问题理解

 我们得到一个正整数数组。 恰好一次，我们可以选择一个连续的段并将其循环旋转任意数量，这实际上意味着我们可以选择段内的任何元素并将其移动到该段的任一端，同时保留剩余元素的相对顺序。 

执行完这个操作后，我们只关心整个数组的最后一个元素和第一个元素之间的差异。 任务是以最大化最终差异的方式选择分段和旋转。 

关键的观察结果是该操作永远不会改变值，只会重新排列它们。 所以我们试图操纵哪个原始元素在位置 1 结束，哪个在位置 n 结束。 

限制以非常可控的方式很小。 所有测试用例中每个数组总共最多有 2000 个元素。 这立即排除了任何具有大常数的三次甚至二次重的每次测试方法，但仍然允许轻松地使用 O(n^2) 或 O(n^2 log n) 解决方案。 

一个天真的错误是认为只有端点很重要或只考虑旋转整个阵列。 另一个常见的错误是假设最佳答案只是 max(a) 减去 min(a)，这忽略了我们不能任意将两个极值放置在两端，除非旋转结构允许。 

一个具体的失败案例是数组`[2, 1, 5]`。 最佳答案是4，通过旋转实现`[2,1,5]`到`[5,2,1]`。 像“独立地将 max 放在末尾并将 min 放在开头”这样的天真的想法会失败，因为这些位置无法独立控制。 

## 方法

 暴力方法尝试每一个可能的部分`[l, r]`以及每一个可能的旋转。 对于每个配置，我们重新计算结果的第一个和最后一个元素并跟踪最佳差异。 由于有 O(n^2) 个段，每个段最多 O(n) 次旋转，并且每次评估都是 O(n)，因此这很快就会变得太大，在直接模拟中每个测试大约为 O(n^4)。 

这种简化来自于认识到我们不关心所选段的内部排列，只关心该段中的哪个元素在旋转后成为其第一个或最后一个边界。 循环旋转允许我们将段中的任何元素移动到段的任一端，这意味着唯一相关的效果是我们可以选择段内的任何一对元素并使它们与其边界相邻。 

因此，问题简化为选择两个位置 i 和 j，使得一个成为第一个元素，另一个成为一次分段操作后的最后一个元素。 然后我们分析使用单段旋转使 i 成为位置 1 或 n 和 j 成为另一端的所有方法。 

结构简化的关键在于，固定了最终的第一个元素后，我们只需要考虑最后一个元素能达到多好，反之亦然。 这导致对于每一种可能的边界选择，检查剩余后缀或前缀中存在哪些极值，这些极值可以通过覆盖一个端点的线段适当地移动。 

这将问题分解为线性扫描，每个位置进行恒定时间检查，根据实现风格产生 O(n) 或 O(n^2) 解决方案，但在限制范围内。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^4) | O(n^4) | O(n) | 太慢了|
 | 最佳| O(n^2) | O(n^2) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们重点关注关键的观察结果，即更改第一个元素的唯一方法是在所选段中包含索引 1，同样，更改最后一个元素的唯一方法是在段中包含索引 n。 否则，这些立场保持不变。 

这将所有有效操作分为三个有意义的类别：接触左端的段、接触右端的段或整个数组。 

1. 首先，考虑根本不触及索引 1 或索引 n。 在这种情况下，答案很简单`a[n] - a[1]`，因为端点保持固定。 这始终是一个基线候选者。 
2. 接下来，考虑包含索引 1 的段。通过选择一个段`[1, r]`，我们可以旋转以使该前缀中的任何元素成为第一个元素。 这意味着我们可以使第一个元素等于任何`a[i]`在哪里`i ≤ r`。 最后一个元素保持不变，除非该段也触及 n。 
3. 同样，考虑包含索引 n 的段。 通过选择`[l, n]`，我们可以旋转，使该后缀中的任何元素成为最后一个元素。 这允许最后一个元素是任何`a[i]`在哪里`i ≥ l`，而第一个元素保持不变，除非 l = 1。 
4. 最后，考虑包含两个端点的段，这意味着`[1, n]`。 在这种情况下，我们可以选择整个数组的任意旋转，因此我们可以有效地选择任何元素作为第一个元素，将任何不同的元素作为最后一个，只要它们可以放置在相对的两端。 这里的最佳选择就是 max(a) - min(a)。 
5. 唯一缺失的情况是我们只更改一个端点。 如果我们只更改第一个元素，我们将位置 i 固定为新的第一个元素，并将 a[n] 保留为最后一个，因此我们最大化`a[n] - min(a[1..n-1])`超过有效的可达结构。 对称地，仅更改最后一个元素给出`max(a[2..n]) - a[1]`。 
6. 我们计算所有这些候选值并取最大值。 

### 为什么它有效

 该操作从根本上受到段边界的限制。 旋转仅排列一个连续块内的元素，因此块外的端点保持固定。 任何试图独立优化两端而不考虑单个段是否会影响两端的策略都会过多计算不可能的配置。 正确的解决方案来自于对每个端点是在所选段内部还是外部进行分类，并穷尽那些一致的情况。 每个可实现的最终配置都恰好属于这些端点包含模式之一，因此采用最好的配置可以保证最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 1:
        print(0)
        continue

    base = a[-1] - a[0]
    best = base

    mn_all = min(a)
    mx_all = max(a)

    best = max(best, mx_all - mn_all)

    mn_prefix = min(a[:-1])
    best = max(best, a[-1] - mn_prefix)

    mx_suffix = max(a[1:])
    best = max(best, mx_suffix - a[0])

    print(best)
```该代码根据所选段是否影响第一个元素、最后一个元素、两者都影响或都不影响，计算四种结构上不同的可能性。 基线保持两个端点不变。 当两个端点都可以在完整段内操作时，全局范围可以提供充分的灵活性。 前缀和后缀情况对应于通过选择锚定在一侧的线段来精确更改一个端点。 简单扫描后，每次测试的每次计算都是恒定时间。 

切片时必须小心。`a[:-1]`和`a[1:]`是安全的，因为 n ≥ 1，但我们明确保护 n = 1，因为否则这些切片将变空并打破最小/最大假设。

 ## 边缘情况

 对于像这样的单元素数组`[7]`，该算法返回 0，因为每次旋转都会使数组保持不变，并且相同端点之间的差异为零。 代码在任何切片之前显式处理此问题，避免无效的最小/最大操作。 

对于单调递增数组，例如`[1,2,3,4]`，最好的做法是旋转整个数组，将 4 放在开头，1 放在结尾，得到 3。全局最大-最小情况直接通过`max(a) - min(a)`。 

对于仅需要更改一个端点即可实现最佳改进的阵列，例如`[5,1,4,3]`，后缀和前缀情况正确隔离了边界可以改进多远，而不需要两个端点同时移动。
