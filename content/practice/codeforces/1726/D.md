 ## 解决方案
 ## 问题理解

 我们得到一个连通的无向图，其中除了树之外还有少量额外的边。 对于每条边，我们必须决定它是红色还是蓝色。 固定着色后，我们查看两个诱导子图：一个仅由红色边缘形成，一个仅由蓝色边缘形成。 每个子图都将顶点分割成连接的组件，我们计算每个子图产生的组件数量。 目标是选择颜色以使这两个分量计数的总和尽可能小。 

关键数量不是每个子图单独的结构，而是边缘在两种颜色之间的分布方式，因为每个边缘同时有助于一个子图中的连接，同时从另一个子图中删除。 

m 至多为 n + 2 的约束是决定性的。 具有 n 个顶点和恰好 n - 1 个边的连通图是一棵树。 添加最多 3 个额外边意味着该图的循环很少，在任何结构意义上最多为三个独立循环。 这严重限制了我们必须考虑的根本不同的跨越结构的数量。 任何尝试将边任意划分为 m/2 或类似大小的两组的解决方案都是立即不可能的，因为 2^m 是 n 的指数。 

一个天真的想法是尝试贪婪地或随机地分配颜色。 这会失败，因为本地决策很容易以强制许多组件的方式断开一种颜色类的连接。 例如，在一个循环中，交替颜色或切割单个“坏”边缘可能会意外增加组件数量。 循环之间的相互作用是全局的：从循环中删除单个边缘会使该颜色的分量恰好增加 1，因此错误地分配循环边缘可能会同时恶化 c₁ 和 c2。 

另一个误导性的情况是多个周期共享边沿。 像“将所有循环边放入一种颜色”这样的贪心规则可能会减少该颜色的分量，但可能会将另一种颜色分割成许多孤立的顶点，从而使 c2 增加太多。 

## 方法

 如果我们尝试暴力破解，我们会将 m 个边分配为红色或蓝色，并重新计算连接的组件两次。 计算组件为 O(n + m)，因此暴力破解成本为 O(2^m · (n + m))。 即使对于 m ≈ n，这也是一个天文数字。 

问题的结构变得易于管理，因为 m 非常接近 n。 具有 n - 1 条边的连通图是一棵树，每条额外的边恰好创建一个循环。 由于最多有三个额外边，因此该图“几乎是一棵树”，只有几个循环。 这意味着图的任何生成树都是所有连接的主干，只有少数边可以改变循环结构。 

关键思想是从生成树开始。 树边对于连接至关重要，而非树边只会产生循环。 如果我们将树的边缘主要分配给一种颜色并仔细分配少数循环边缘，我们就可以准确控制每种颜色产生的分量数量。 

更深入的观察是，最小化 c₁ + c2 相当于最大化两个颜色诱导结构之间“共享有用”的边数。 树边本质上是不对称的：每个树边对于连接性至关重要，因此仔细分割它们可以确定基线组件。 循环边可用于“修复”一种颜色的连接性，而不会严重损坏另一种颜色，但由于最多有三个，我们可以强力强制它们的分配模式或以受控方式单独处理它们。 

这将问题简化为构建生成树，然后处理恒定数量的剩余边，我们可以在其中显式测试配置或贪婪地分配它们，而不会出现组合爆炸的风险。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解边缘颜色 | O(2^m·n) | O(2^m·n) | O(n + m) | 太慢了|
 | 生成树 + 句柄 ≤ 3 条额外边 | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 我们围绕生成树构建解决方案，并单独处理非树边缘。 

1. 我们首先使用 DFS 或 DSU 构造图的任意生成树。 

该树将定义一个基本结构，其中所有顶点都无环连接。 然后，每个非树边都被识别为闭合循环的额外边。 
2. 我们标记属于生成树的所有边。 

这些边是确保连接性所需的最小边集。 任何树边缘的删除都会分裂树，因此它们的分配是组件计数的主要驱动因素。 
3. 我们收集不属于生成树的所有剩余边。 

由于 m ≤ n + 2，因此最多有 3 个这样的边。 这些边与循环形成边完全对应。 
4. 我们尝试将这几个额外边的所有可能分配为红色或蓝色。 

由于最多有 3 条边，因此最多有 2³ = 8 种情况。 对于每种情况，我们通过考虑每种颜色中“激活”的周期来模拟它如何影响连接性。 
5. 对于每个额外边缘的分配，我们计算每种颜色将有多少个分量。 

如果所有树的边缘都是一种颜色，则单独的树边缘可确保单个连接的结构。 每次我们从颜色中删除树边缘或无法通过循环边缘替换连接时，我们都会增加组件数量。 我们使用 DSU 对此进行一致评估。 
6. 我们选择最小化 c₁ + c2 的分配并相应地构造最终的着色字符串。 

重要的结构点是树的边缘定义了刚性的主干。 可以改善目标的唯一灵活性来自于分布少数循环边缘，并且该空间小到足以耗尽。 

### 为什么它有效

 任何连通图都可以简化为生成树加上额外的边。 生成树边是唯一移除直接增加连通分量的边。 由于额外边的数量是恒定的，唯一有意义的组合选择是这些少数边如何与树结构相互作用。 穷尽他们的所有任务可以保证我们不会错过任何可以改善 c₁ 和 c2 之间权衡的配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1
        return True

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        edges = []
        for i in range(m):
            u, v = map(int, input().split())
            edges.append((u - 1, v - 1, i))

        dsu = DSU(n)
        used = [False] * m
        extra = []

        for u, v, i in edges:
            if dsu.union(u, v):
                used[i] = True
            else:
                extra.append(i)

        # at most 3 extra edges
        k = len(extra)

        best = m + 5
        best_mask = 0

        for mask in range(1 << k):
            red = DSU(n)
            blue = DSU(n)

            for u, v, i in edges:
                if i in extra:
                    idx = extra.index(i)
                    if (mask >> idx) & 1:
                        red.union(u, v)
                    else:
                        blue.union(u, v)
                else:
                    red.union(u, v)
                    blue.union(u, v)

            c1 = len({red.find(i) for i in range(n)})
            c2 = len({blue.find(i) for i in range(n)})

            if c1 + c2 < best:
                best = c1 + c2
                best_mask = mask

        res = ['0'] * m
        for u, v, i in edges:
            if i in extra:
                idx = extra.index(i)
                if (best_mask >> idx) & 1:
                    res[i] = '1'
            else:
                res[i] = '1'

        out.append("".join(res))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案首先使用 DSU 构建生成树，将闭合循环的边标记为“额外”。 由于最多有三个这样的边，因此我们枚举了它们在红色和蓝色之间的所有可能分配。 对于每项任务，我们都会重建两个 DSU 结构，每个结构对应一种颜色，并计算每个结构产生多少个连通分量。 存储最佳配置。 

一个微妙的点是，在此实现中，树边始终包含在两个 DSU 中。 这反映了基线连接是共享的，而只有循环边决定图的分割方式。 然后，DSU 组件计数步骤可以正确捕获由于缺少循环强化而导致的碎片。

 ## 边缘情况

 一个关键的边缘情况是当图已经是一棵树时。 在这种情况下，没有额外的边，因此两个 DSU 的行为相同，并且每种配置都会产生 c₁ = c2 = 1。该算法自然会返回具有相同颜色的所有边，并且有效地跳过枚举步骤。 

另一种情况是所有额外的边形成共享一个顶点的重叠循环。 即便如此，由于它们的数量最多为三个，枚举所有分配可以确保我们评估“聚集在一种颜色”和“拆分不同颜色”行为。 DSU 重新计算正确捕获这些周期是减少还是增加碎片。 

最后一种情况是，将所有额外边缘分配给一种颜色似乎有益，但实际上增加了另一种颜色的分量。 详尽的检查保证了直接比较这种不对称的权衡，防止任何贪婪的偏见错过最佳平衡。
