 ## 问题理解

 我们得到一个长度平衡的括号字符串$2n$。 该字符串中的每个位置都被视为图中的一个顶点。 两个顶点$i$和$j$当子串来自时，由无向边连接$i$到$j$自己形成一个平衡的括号序列。 

任务不是显式地构建该图（这会太大），而是确定它包含多少个连接的组件。 

一个关键的困难是边依赖于子串的全局结构而不是局部邻接。 尽管原始字符串已经是平衡的，但大多数子字符串并不平衡，因此该图以隐式方式稀疏，必须以组合方式来理解。 

这些约束迫使我们采用线性或近线性解决方案。 所有测试用例的总长度最多为$10^5$，因此任何检查子字符串或尝试逐对模拟连接的算法都会立即失败。 甚至$O(n^2)$子字符串的扫描是不可能的，因为单个测试用例已经可以达到$10^5$。 

一个微妙的边缘情况源于以下事实：每个平衡括号字符串都可以唯一地分解为原始段，其中原始段是平衡的最小前缀。 例如，`"()(())"`分裂成`"()"`和`"(())"`。 事实证明，图形结构完全取决于这些原始块的排列方式。 

一种简单的方法是尝试通过使用前缀和或堆栈检查每个子字符串的有效性来连接索引。 这会错误地表明连接性非常密集，但它忽略了平衡子串必须对应于内部永远不会变负的精确零和段。 该约束将边缘限制在原始块内部。 

## 方法

 暴力解决方案将检查每一对$i < j$，验证是否$s[i..j]$使用堆栈或前缀平衡检查进行平衡，然后将这些顶点合并到 DSU 中。 检查单个子串的成本$O(n)$在最坏的情况下，有$O(n^2)$子串，导致$O(n^3)$的行为，远远超出了可行的限度。 

我们可以通过注意到检查平衡子串可以简化为前缀和来改进这一点：如果子串的总余额为零并且其中没有前缀低于起始级别，则子串是平衡的。 即使有前缀和，所有对的迭代仍然是二次的。 

关键的结构见解是连通性完全由平衡序列的原始分解控制。 每个基元块都是一个最小平衡前缀，返回到平衡零并且内部永远不会接触零。 在这样的块内，任何顶点都可以通过有效的平衡子串连接到任何其他顶点，因为该结构的行为就像一个独立的组件。 然而，在两个不同的基元块之间，不存在跨越边界的平衡子串，因为任何跨越都会违反前缀平衡约束。 

因此，每个图元段恰好对应于图中的一个连接组件。 该问题简化为在扫描字符串时计算前缀和返回零的次数。

 | --- | --- | --- | --- |
 | 蛮力 |$O(n^3)$|$O(n)$| 太慢了|
 | 最优（原始计数）|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 从左到右遍历字符串，同时保持平衡计数器递增`'('`并递减`')'`。 这跟踪了我们在括号结构中的嵌套深度。 
2. 每当余额计数器变为零时，我们就完成了一个原始的平衡段。 这意味着从最后一个切割点到当前位置的子字符串是一个最小的独立有效块。 
3. 每次余额返回到零时，增加答案，因为每个此类事件都标志着图中断开组件的结束。 
4. 继续直到字符串末尾，确保所有基元都被计数。 

步骤 2 背后的直觉是，返回零的平衡前缀不能在不违反前缀约束的情况下分割成更小的平衡部分，因此它充当结构单元。 

### 为什么它有效

 原始段是一个最大连续区域，其中运行平衡从零开始，内部严格保持正值，仅在结束时返回到零。 任何从一个原始块内部开始并在其外部结束的平衡子串必须穿过中间平衡为零的点，这将强制分解。 这可以防止任何边跨图元边界连接顶点。 在图元块内，平衡子串只能连接同一块内的顶点，因此块中的所有顶点都可以通过有效边相互可达。 这在原始块和连接的组件之间创建了一对一的对应关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    bal = 0
    components = 0

    for ch in s:
        if ch == '(':
            bal += 1
        else:
            bal -= 1

        if bal == 0:
            components += 1

    print(components)
```该解决方案独立处理每个测试用例。 平衡计数器以恒定的时间跟踪每个字符的前缀有效性。 每次计数器返回到零时，原始块就结束，并且我们增加组件计数。 

关键的实现细节是，除了通过余额归零隐式重置之外，我们永远不会重置任何东西。 这避免了任何显式分段或子字符串处理的需要。

 ## 边缘情况

 一种关键的边缘情况是整个字符串是一个深度嵌套结构，例如`"(((())))"`。 在这种情况下，余额仅在最后返回零一次，因此算法正确地输出一个分量。 任何根据本地模式进行分割的尝试都会错误地过度计数。 

另一种情况是完全交替的基元，例如`"()()()"`。 每两个字符后余额为零，产生三个组件。 该算法自然地将每个重置捕获为分割点，并且这些重置之间没有子串交叉，因此连接性仍然限制在每对内。 

混合结构如`"(())()()"`确认嵌套基元和平面基元可以共存。 第一次重置发生在嵌套块之后，后续重置发生在每个嵌套块之后`"()"`，恰好产生三个组件。 这与平衡子字符串不能跨越这些重置点的事实相匹配，因为这样做需要违反字符串内的前缀平衡。
