 ## 解决方案
 ## 问题理解

 我们被赋予了一个公司层次结构，形成了有根树。 除了最高层经理没有直接主管外，每个员工都只有一名直接主管。 我们可以将其视为一棵有向树，其中边从员工指向其主管，每个节点最终都通向根。 

每个员工也属于一个“组”，它只是一个整数标签。 系统升级后，员工不仅要对自己的组负责，还要对其主管链上的所有组负责，直到根部。 

任务是计算每个员工从该员工到树根的路径上出现了多少个不同的组标签。 

因此，问题简化为：对于有根树中的每个节点，计算沿着到根的路径的节点标签集中唯一值的数量。 

约束条件$N \le 10^6$迫使我们以本质上线性或接近线性的时间为目标。 任何通过重复向上行走来重新计算每个节点信息的方法都会降级为$O(N^2)$在链状树中，这是不可接受的。 甚至$O(N \log N)$由于这个规模的常数因素很大，必须仔细设计方法。 

一个微妙的边缘情况是深链，其中每个节点都有一个唯一的组。 在这种情况下，节点的答案$i$只是它的深度，任何重新启动每个节点计数的解决方案都会超时。 

另一个边缘情况是所有节点共享同一组。 每个节点的正确答案是 1，但如果不仔细处理重复项，简单的合并结构可能会过度计算。 

## 方法

 暴力方法很简单。 对于每个员工，沿着主管链向上走直到根，将所有组 ID 收集到一个集合中，并返回其大小。 这是正确的，因为它直接遵循问题的定义：我们明确地收集沿监督路径可见的所有组。 

然而，这种方法太慢了。 在最坏的情况下，树是单条长度的链$N$。 对于每个节点，我们遍历到$O(N)$祖先，并设置插入成本$O(1)$平均，给予$O(N^2)$总操作。 和$N = 10^6$，这已经远远超出了极限。 

关键的观察是我们沿着根路径重复计算类似前缀的信息。 每个节点的答案仅取决于从根到该节点的路径上迄今为止看到的组值集。 如果我们按照从根到叶的遍历顺序处理节点，我们就可以维护一个表示当前路径的全局结构。 

困难在于处理唯一性：我们必须知道当前路径上是否已经存在一个组。 这建议维护活动 DFS 路径上组的频率计数。 当进入一个节点时，我们添加它的组； 离开时，我们将其删除。 路径上不同组的数量就是具有正频率的键的数量。 

这将问题变成了经典的“树上的 DSU/具有路径状态的 DFS”模式，但需要仔细的频率跟踪。 我们通过维护增量状态来避免重新计算。 

挑战在于$N$很大，所以必须考虑递归深度和开销。 迭代 DFS 通常更安全，但递归 DFS 在 PyPy 中是可以接受的，或者如果仔细控制的话，递归限制会增加。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（走到每个节点的根）| O(N²) | O(1) 额外 | 太慢了|
 | 路径上带有频率图的 DFS | O(N) | O(N) | 已接受 |

 ## 算法演练

 ## 算法演练

 1. 通过将主管指针反转为树结构，构建从子关系到父关系的邻接列表。 这允许从根向下而不是向上遍历，这对于有效重用路径信息是必要的。 
2. 识别根节点，即主管为 0 的节点。这是遍历的唯一起点，因为每个节点最终都会连接到它。 
3. 从根开始运行深度优先遍历，维护两个结构：存储每个组在当前根到节点路径上出现的次数的频率字典，以及当前有多少个不同组处于活动状态的计数器。 
4. 当进入一个节点时，增加其分组的频率。 如果该频率变为1，则意味着该组是在当前路径上新引入的，因此我们增加不同组计数器。 
5. 将当前的不同组计数器存储为该节点的答案，因为它准确地表示其根路径上的唯一组的数量。 
6. 递归到所有子级，向下传播更新的状态。 
7. 完成所有子节点后，通过降低当前节点组的频率来回溯。 如果其频率下降到 0，我们将减少不同的计数器，因为该组不再存在于活动路径中。 

这样做的原因是，在 DFS 期间的任何时刻，维护的状态都准确地表示当前根到节点路径上的组的多重集。 由于作为此遍历的一部分，每个节点都被访问一次，因此每个节点的答案都是使用其路径状态的一致快照来计算的。 

## Python 解决方案```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    n = int(input())
    parent = list(map(int, input().split()))
    group = list(map(int, input().split()))

    children = [[] for _ in range(n + 1)]
    root = -1

    for i in range(1, n + 1):
        p = parent[i - 1]
        if p == 0:
            root = i
        else:
            children[p].append(i)

    ans = [0] * (n + 1)
    freq = {}
    distinct = 0

    def dfs(u):
        nonlocal distinct

        g = group[u - 1]
        freq[g] = freq.get(g, 0) + 1
        if freq[g] == 1:
            distinct += 1

        ans[u] = distinct

        for v in children[u]:
            dfs(v)

        freq[g] -= 1
        if freq[g] == 0:
            distinct -= 1

    dfs(root)

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```该解决方案首先将主管指针反转到子邻接列表中。 这是必要的，因为自然输入描述了父指针，但 DFS 状态自然是从根到叶维护的。 

这`freq`字典跟踪每个组在当前递归堆栈中出现的次数。 这`distinct`变量避免重新计算字典大小，否则在规模上会太慢。 增量更新至关重要。 

回溯步骤是必不可少的。 从递归返回后如果不删除该组，状态将在分支之间泄漏并错误地对组进行计数。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N) | 每个节点只进入和退出一次，并且所有频率更新都是 O(1) 摊销 |
 | 空间| O(N) | 最坏情况下的邻接表加上递归堆栈和频率图 |

 该算法非常适合约束，因为每个操作都是每个节点的持续工作，并且内存使用量随着员工数量线性增长。

 ## 边缘情况

 某单节点公司暴露了算法在DFS之前是否正确初始化了根状态。 遍历从节点 1 开始，添加其组，并立即记录答案 1，而不会出现递归问题。 

统一组树测试频率跟踪是否避免过度计数。 每个节点都会重复添加相同的组，但不同的计数器仅在根处增加一次，并且不会再增加，从而产生一致的 1。 

具有重复组值的倾斜树可确保正确实施回溯。 当从分支返回时，未能减少频率会错误地将组传播到不相关的子树中，从而导致答案膨胀。 DFS 删除步骤保证每个子树只看到自己的活动路径状态。
