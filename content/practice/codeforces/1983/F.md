 ## 解决方案
 ## 问题理解

 给定一个数组，我们查看每个可能的长度至少为 2 的连续子数组。 对于每个子数组，我们计算一个值，定义为该子数组内所有索引对中的最小异或。 换句话说，在一个段内，我们考虑所有元素对，计算它们的异或，并保留最小的一个。 该最小值成为子阵列的“成本”。 

任务不是显式计算所有这些值并对它们进行排序，而是确定所有子数组成本中的第 k 个最小值。 

这些限制立即迫使人们提出不同的观点。 子数组的总数是 n 的二次方，并且每个子数组包含潜在的二次对。 即使以一种简单的方式计算一个子数组的答案也已经太慢了。 对于 n 高达 100,000 次的跨测试，任何比每次测试的近线性或线性对数更差的方法都是不可行的。 

不明显的困难是子数组值取决于其中的最佳对，而不是端点。 一个天真的想法是认为只有相邻对才重要，但像 [a, b, c] 这样的子数组可能与 (a, c) 具有最小异或，完全跳过 b。 

一些边缘案例说明了陷阱。 

如果所有元素都相等，则每个 XOR 都为零，因此每个子数组值都为零。 无论 k 如何，答案始终为零。 任何试图“找到不同的异或”的方法仍然有效，但前提是它正确地考虑了所有子数组中的重复项。 

如果数组像 [1, 2, 4, 8] 那样严格递增，则 XOR 不是单调的，并且较长范围内的值可能比较短范围内的值更大。 任何假设子数组大小单调行为的方法都会失败。 

如果数组具有像 [x, y, x] 这样的局部模式，则整个段中的最佳 XOR 可能来自给出零的相等端点，即使相邻的 XOR 很大。 这打破了仅贪婪邻接推理。 

## 方法

 蛮力的想法很简单。 对于每个子数组，枚举其中的所有对，计算它们的 XOR，取最小值，存储它，然后对所有结果进行排序并选择第 k 个元素。 这是正确的，但从根本上来说太昂贵了。 有 O(n^2) 个子数组，每个子数组需要 O(n^2) 对检查，导致最坏情况为 O(n^4)，这远远超出了任何可行的限制。 

我们可以通过重新思考子数组的值到底是什么来逐步改进。 段内的最小异或总是通过二进制表示形式“最接近”的两个元素来实现。 这表明我们应该避免检查段内的所有对，而是维护一个可以有效报告不断增长的数字集中最小异或对的结构。 

一个关键的转换是反转问题：我们不直接计算子数组值，而是计算有多少个子数组最多具有 X 值。如果我们能够有效地回答这个函数，我们就可以对答案进行二分搜索。 剩下的挑战变成：对于固定的 X，检查子数组是否包含 XOR ≤ X 的对。 

这是一个经典的二元 trie 结构的滑动窗口。 我们维护一个窗口并支持插入、删除和查询最小异或伙伴的值。 如果在任何时候窗口包含一对 XOR ≤ X，则该子数组有效。 我们可以使用两指针方法计算所有有效子数组。 

trie 允许我们检查每个新元素在窗口中是否存在产生 XOR ≤ X 的较早元素，并相应地缩小或扩展窗口。 

这将每次检查的问题减少到 O(n log A)，并且通过答案空间上的二分搜索，解决方案变得高效。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^4) | O(n^4) | O(n^2) | O(n^2) | 太慢了 |
 | 二分查找 + trie 窗口 | O(n log A log A) | O(n log A log A) | O(n log A) | O(n log A) | 已接受 |

 ## 算法演练

 我们定义一个函数`count(X)`计算有多少个子数组具有最小对 XOR ≤ X。 

1. 我们使用二进制 trie 存储当前窗口中数字的二进制表示。 这种结构允许我们查询任何值与现有元素可以实现的最小异或。 
2.我们维护两个指针`l`和`r`。 当我们尝试包含尽可能多的元素时，右侧指针会扩展窗口。 
3.对于位置处的每个新元素`r`，我们将它插入到 trie 中。 然后我们检查当前窗口中是否存在异或≤X的任何对。 
4. 如果存在这样的一对，则窗口有效，因此我们计算所有以`r`并从任何地方开始`l`到`r`, 贡献`r - l + 1`子数组。 
5. 如果条件无效或者我们想要强制执行最低限度，我们会移动`l`向前，从 trie 中删除元素，直到条件再次有效。 
6. 我们累加所有的计数`r`。 
7. 最后，我们对答案进行二分查找。 最小可能的 XOR 是 0，最大的约为 2^30，所以我们在这个范围内搜索。 

### 为什么它有效

 关键的不变量是，在任何时候，trie 都精确包含当前窗口中的元素，并且窗口被维护，以便在可能的情况下满足条件“存在一对 XOR ≤ X”。 当右端点扩展时，每个子数组只计算一次，而左指针确保我们不会过度计算无效段。 二分搜索包装了这个单调谓词：如果值 X 有效，则任何更大的值也有效，因为允许更大的 XOR 只会增加有效对的集合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Trie:
    def __init__(self):
        self.child = [[-1, -1]]
        self.cnt = [0]

    def insert(self, x):
        node = 0
        self.cnt[node] += 1
        for b in range(30, -1, -1):
            bit = (x >> b) & 1
            if self.child[node][bit] == -1:
                self.child[node][bit] = len(self.child)
                self.child.append([-1, -1])
                self.cnt.append(0)
            node = self.child[node][bit]
            self.cnt[node] += 1

    def remove(self, x):
        node = 0
        self.cnt[node] -= 1
        for b in range(30, -1, -1):
            bit = (x >> b) & 1
            node = self.child[node][bit]
            self.cnt[node] -= 1

    def min_xor(self, x):
        node = 0
        res = 0
        for b in range(30, -1, -1):
            bit = (x >> b) & 1
            if self.child[node][bit] != -1 and self.cnt[self.child[node][bit]] > 0:
                node = self.child[node][bit]
            else:
                node = self.child[node][bit ^ 1]
                res |= (1 << b)
        return res

def count_leq(a, x):
    n = len(a)
    tr = Trie()
    l = 0
    ans = 0

    for r in range(n):
        tr.insert(a[r])

        while l <= r:
            best = tr.min_xor(a[r])
            if best <= x:
                break
            tr.remove(a[l])
            l += 1

        ans += (r - l + 1)

    return ans

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        lo, hi = 0, (1 << 30) - 1
        while lo < hi:
            mid = (lo + hi) // 2
            if count_leq(a, mid) >= k:
                hi = mid
            else:
                lo = mid + 1

        print(lo)

if __name__ == "__main__":
    solve()
```trie 被实现为二进制结构，其中每个节点跟踪子指针和子树计数。 插入和删除保持了滑动窗口使用的正确性。 这`min_xor`函数通过贪婪地匹配 trie 中的位来计算给定值的最佳可实现的 XOR 配对。 

两指针循环`count_leq`确保我们只保留条件可行的窗口，并且每个右端点准确贡献有效起始位置的数量。 

二分搜索应用于答案空间，利用“值≤X的子数组的数量”的单调性。

 ## 边缘情况

 对于像这样的输入`[7, 7, 7, 7]`，每对都有 XOR 0，因此每个子数组值都是 0。trie 永远不会找到非零改进，二分搜索立即崩溃为 0。滑动窗口仍然正确地计算所有子数组，因为每个窗口都满足任何 X ≥ 0 的条件。 

对于`[1, 1000000000]`，只有一对存在，答案是它们的异或。 trie 恰好包含两个元素，并且最小 XOR 查询返回该单个值，没有任何歧义，这表明该算法可以优雅地处理最小结构，而不依赖于窗口调整。
