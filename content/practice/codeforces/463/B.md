 ## 问题理解

 我们得到了一系列排列成直线的塔序列，从位置 0 开始到位置 n。 第一个塔的高度固定为 0，其他每个塔都有给定的高度。 玩家从能量为零的塔 0 开始，严格向前移动，一次一步，从塔 k 到塔 k+1。 

每次移动都会根据当前高度和下一个高度之间的差异来改变能量。 如果下一个塔较低，则能量增加，如果下一个塔较高，则能量减少。 关键的限制是在旅途中的任何时候都不允许能量低于零。 

我们可以通过每增加一个单位花费一美元来增加任何塔的高度，并且我们希望最大限度地减少花费的总美元，以便从 0 到 n 的旅程变得可行。 

约束 n ≤ 100000 立即排除了尝试所有可能的高度修改或模拟昂贵的配置搜索的任何方法。 任何解在 n 中都必须是线性的或接近线性的。 即使 O(n log n) 也是可以接受的，但任何二次的都不能接受。 

一种幼稚的方法可能会尝试模拟旅程，每当能量变为负数时，就在没有明确策略的情况下贪婪地增加一些先前或当前的高度。 这会失败，因为早期的调整会以非局部方式影响后来的转换。 

当局部修复目光短浅时，就会出现微妙的失败情况。 例如，如果高度为：```
n = 3
h = [5, 1, 5]
```贪婪模拟可能会修复从 5 到 1 的下降，但后来在 1 到 5 时仍然失败，导致冗余或错误的升级。 正确的解决方案必须对沿途遇到的最严重赤字进行全球推理，而不是一步一步地做出反应。 

## 方法

 蛮力的想法是模拟旅程，每当能量变为负值时，尝试增加一些塔架高度来补偿。 人们可以尝试在每个故障点花钱的所有选择。 这很快就会变成组合性的：每次修正都会改变未来的差异，在最坏的情况下，我们可能会反复重新考虑之前的决定。 当 n 达到 100000 时，即使是几千个分支修正也足以爆炸超出极限。 

关键的见解是停止从能源演化的角度思考，而是重写真正重要的东西。 每次移动都会产生一个差值 h[k] - h[k+1]。 随着时间的推移对这些进行求和，得出仅取决于前缀行为的累积能量。 能量出现问题的唯一时间是当这些差异的前缀和降至零以下时。 

重新排列表达式表明，唯一危险的时刻是当高度 h[i] 大于我们可以从累积能量中承受的任何值时。 我们可以保持我们拥有的“自由预算”并确保它永远不会变成负值，而不是明确地跟踪能源。 我们唯一需要付款的时候是当减少的金额无法弥补之前的增加金额时。 

一个更简单的解释出现了：每当我们遇到一个比之前所有有效高度都大的高度时，我们就必须“付费”来提升我们的基线，这样我们就可以在没有负能量的情况下到达它。 这将问题简化为跟踪运行的最大高度并累积相对于起始高度的不足。 

因此，最佳解决方案是线性的：我们从左到右扫描，保持迄今为止看到的最高高度，每当下一个高度大于我们当前的有效容量时，我们就支付差额。

 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |

 ## 算法演练

 我们将这段旅程重新解释为保持基线高度，保证非负能量。 

1. 从等于 0 的基线开始，因为我们从高度为 0、能量为零的塔 0 开始。 我们还将答案初始化为 0，代表花费的总金额。 
2. 从 1 到 n 迭代 pylon。 在每个步骤中，将当前高度与基线要求进行比较。 
3. 如果当前高度大于基线，我们必须增加基线以匹配它。 这个差异准确地代表了我们此时必须花费多少美元，因为如果没有有效地升起早期的塔，当踏入这个更高的塔时，能量将变成负值。 
4. 将这个差异添加到答案中。 该模型花钱增加合适的塔架，以便过渡保持可行。 
5. 将基线更新为其当前值和当前高度的最大值。 
6. 继续，直到处理完最后一个塔架。 累计成本为最低所需支出。 

### 为什么它有效

 关键的不变量是，在处理塔 i 后，基线等于迄今为止看到的最大高度。 这保证了所有先前处理的转换都是安全的，这意味着移动的前缀没有负能量。 每当新的高度超过这个最大值时，避免该步骤出现负能量下降的唯一方法就是通过升高一些较早的塔架来补偿它。 由于无论在何处应用，每个单位的增加成本都是一美元，因此在遇到新的最大值时逐步增加基线是最佳的，并且永远不会超额支付。 任何延迟的修正仍然需要匹配相同的高度差距，因此这种贪婪的积累是最小的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    h = list(map(int, input().split()))

    current_max = 0
    cost = 0

    for x in h:
        if x > current_max:
            cost += x - current_max
            current_max = x

    print(cost)

if __name__ == "__main__":
    solve()
```该实现保持了迄今为止所见的运行最大高度。 每当新的高度超过它时，我们就会将差额添加到成本中。 这直接编码了我们必须“提升”早期地形以迎接新峰值的想法。 

一个常见的错误是尝试直接使用前缀差异来模拟能量。 这种方法使问题变得复杂并引入了不必要的状态。 贪婪最大跟踪方法完全避免了显式能量跟踪。 

另一个微妙之处是我们从不显式调整数组中的任何内容。 推理依赖于等价性：增加较早的塔架或概念上增加基线会对所有未来的差异产生相同的效果。

 ## 边缘情况

 像这样的最小情况`n = 1, h = [1]`表明当第一个塔超过零时我们仍然必须花费。 该算法正确地添加了`1 - 0 = 1`立即地。 

严格递减序列，例如`5 4 3 2`第一步之后绝不会触发额外支出。 第一个值设置所需的基线，之后的所有值都安全地低于它。 该算法通过更新来处理这个问题`current_max`第一步为 5，并且不再更改，总成本为 5。 

严格递增的序列，例如`1 2 3 4`因为每一个新的高度都超过了之前的最大值，因此迫使每一步都支出。 该算法累积地添加差异：1，然后1，然后1，然后1，匹配不断提高基线的直观需要。
