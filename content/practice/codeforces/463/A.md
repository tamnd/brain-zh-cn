[CF 463A - 凯萨和糖](https://codeforces.com/problemset/problem/463/A)

 **评分：** 1200
 **标签：** 暴力破解、实施
 **求解时间：** 1m
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们得到了以美元表示的固定金额，以及超市中的糖选择清单。 每个期权都有一个以美​​元和美分表示的价格。 Caisa 可以准确地选择一种糖，用他可用的钱来支付，如果他的钱多于所需的钱，还可以找零。 不寻常的细节是，商店退回部分糖果而不是美分，而他收到的糖果数量恰好等于他找零的美分数量，隐含的上限是美分总是标准化的，因此将 100 美分兑换成 1 美元后最多剩下 99 美分。 

任务是选择凯萨能买得起的单一糖类型，并最大限度地增加他找零时获得的糖果数量。 如果没有负担得起的糖类型，答案是-1。 

输入大小很小：最多 100 个选项。 这立即排除了对性能的任何担忧； 即使对所有项目进行双重循环也是微不足道的。 对列表进行线性扫描就足够了。 

当所有物品总计太贵时，就会出现微妙的边缘情况。 例如，如果凯萨有 5 美元，而每颗糖的价格至少为 6 美元，则不可能购买，答案必须为 -1。 另一种情况是，多种商品价格都可以承受，但其中一种价格较低，而另一种则能带来更多的零钱； 最佳选择不是最便宜的商品，而是最大化减去后的余数（以美分为单位）的商品。 

一个可能使天真的方法感到困惑的具体例子是选择成本最低的项目而不是最大化变化。 假设Caisa有10美元。 一件商品售价 9 美元 70 美分，另一件售价 7 美元 0 美分。 第一个仅产生 30 美分零钱，而第二个产生 300 美分零钱，对应于 3 美元和 0 美分，因此 0 块糖果。 如果不仔细计算以分为单位的余数，很容易比较错误。 

## 方法

 暴力解决方案自然会从约束中得出。 我们迭代每种糖类型，检查 Caisa 是否能负担得起，计算美分的变化，并跟踪最大剩余金额。 由于最多有 100 个项目，因此这最多是 100 次算术检查，可以忽略不计。 

关键的观察结果是，问题完全是每个项目的局部问题。 选择之间没有交互作用，没有组合结构，也不需要跨多个选择进行优化。 每种糖类型独立地产生一个候选值：从可用资金中减去其价格后还剩下多少美分。 

我们将所有内容都转换为美分以避免浮点推理。 如果Caisa有s美元，那就变成100美分。 每件物品的成本为 100xᵢ + yᵢ 美分。 如果成本超过可用资金，我们就会跳过它。 否则，我们计算余数并更新最佳答案。 

蛮力方法已经是最优的，因为输入大小是恒定有界的并且很小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 已接受 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 通过计算 100 * s 将可用资金转换为美分。 这确保了所有比较都在单一单位系统中进行，从而消除了美元和美分之间的任何歧义。 
2. 最好将变量初始化为-1。 这将在所有负担得起的选项中存储最大的美分变化。 
3. 对于每种糖类型，使用 100 * xᵢ + yᵢ 将其价格转换为美分。 这给出了与预算相同单位的可比数量。 
4. 如果价格超过可用金额，请跳过此选项，因为无法购买。 
5. 否则将变化计算为（预算 - 价格）。 使用模 100 提取美分部分，因为糖果对应于标准化后剩余找零中的美分。 
6. 如果该值大于当前最佳值，则更新最佳值。 
7.处理完所有项目后，输出最佳值。 如果没有找到有效的项目，最好保持 -1。 

### 为什么它有效

 每种糖类型恰好产生一个独立的候选值，即购买后剩余的美分数。 由于 Caisa 只购买一件商品，因此问题就简化为在一组有限的独立评估中选择最大值。 将所有内容转换为美分可以保留顺序并确保不损失精度。 该算法保持了不变式，即最佳值始终是迄今为止处理的所有可负担商品中看到的最大变化美分，因此最终值是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, s = map(int, input().split())
    budget = s * 100

    best = -1

    for _ in range(n):
        x, y = map(int, input().split())
        cost = x * 100 + y

        if cost <= budget:
            change = budget - cost
            sweets = change % 100
            if sweets > best:
                best = sweets

    print(best)

if __name__ == "__main__":
    main()
```该解决方案首先将预算标准化为美分，以便比较保持一致。 在进行任何算术之前，每个项目也会转换为美分，从而避免混合单位错误。 

关键的实现细节是对剩余的变化使用模 100。 由于糖果相当于整美元标准化后剩余金额中的美分，因此只有除以 100 后的余数才重要。 仅跟踪该值可以避免不必要的计算。 

边缘处理是隐式的：如果没有项目满足成本 <= 预算，则最好永远不会从 -1 更新。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, s = map(int, input().split())
    budget = s * 100

    best = -1

    for _ in range(n):
        x, y = map(int, input().split())
        cost = x * 100 + y
        if cost <= budget:
            best = max(best, (budget - cost) % 100)

    return str(best)

# provided sample
assert run("5 10\n3 90\n12 0\n9 70\n5 50\n7 0\n") == "50"

# minimum case, no affordable item
assert run("1 1\n2 0\n") == "-1"

# exact budget match, zero change
assert run("2 5\n5 0\n3 0\n") == "0"

# multiple options, best is not cheapest
assert run("3 10\n9 99\n9 50\n8 0\n") == "50"

# all affordable, check modulo behavior
assert run("3 10\n1 10\n1 20\n1 30\n") == "90"

 ## 边缘情况

 一种极端情况是所有物品都太贵。 在这种情况下，循环永远不会更新初始值 -1，并且输出仍保持 -1。 例如，预算为 100 美分，商品成本为 200 美分，检查失败并且不执行找零计算，从而正确保留哨兵。 

另一种情况是多种商品价格实惠，但剩余物相同。 例如，两件商品可能都剩下 30 美分。 该算法自然地处理这个问题，因为它只跟踪最大值，相等的值不会改变结果。 

最后一种情况是零钱是 100 美分的倍数。 在这种情况下，模运算的结果是 0，这正确地代表了零糖果。
