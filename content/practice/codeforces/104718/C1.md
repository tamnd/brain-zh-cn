 ## 问题理解

 我们得到一个网格，代表配对对象的混乱排列。 每个整数恰好出现两次，我们可以将每个数字视为代表一个“对”，理想情况下它们应该在网格中彼此相邻。 

如果两个单元格共享一条边（即上、下、左或右），则它们被视为相邻。 目标是重新排列网格，以便对于每个数字，它的两次出现变得相邻。 我们不能改变价值观，只能改变他们的立场。 

任务是确定必须移动的元素的最小数量（或者等效地，必须重新分配其内容的单元格的最小数量），以便每对最终都相邻。 

网格大小的限制达到 80 x 80，即最多 6400 个单元格。 尝试所有布局排列的解决方案是不可能的，因为即使全局重新排列的推理也会导致阶乘复杂性。 我们需要一种方法，将问题简化为每对独立决策或网格上的结构化计数。 

一个微妙的点是，移动一对端点可以同时影响其他对的正确性。 以任意顺序一对一修复配对的天真贪婪方法可能会失败，因为早期的选择可能会阻碍后续配对的最佳放置。 

例如，如果两对在像 2×2 块这样的紧密区域中重叠，贪婪地固定第一对而不考虑第二对可能会迫使以后进行额外的移动，即使不同的初始分配会最小化总变化。 

## 方法

 蛮力的想法是尝试将每对相同的数字分配给网格中的两个相邻单元格，同时最小化与原始位置不同的单元格数量。 从概念上讲，我们为每个数字 x 选择网格中所有可能的相邻单元对之一来承载其两次出现，然后计算其原始位置中有多少未被使用的成本。 

这立即变得棘手。 如果有 k 个不同的数字，每个数字对于一个端点都有 O(nm) 种可能的放置方式，从而导致大约 O((nm)^k) 个配置。 即使对于小网格，这也会爆炸。 

关键的见解是扭转观点。 我们不考虑每对应该去哪里，而是考虑已经代表有效邻接的网格边缘。 每对相同的数字必须占据两个相邻的单元格。 因此，每个数字必须分配给网格图的一条边。 

现在结构变得清晰了：每个单元最多参与四个邻接边，并且每个边最多可以服务一对。 我们希望在网格图中选择一个覆盖所有对的匹配，从而最大化原始网格中已经“自然相邻”的对的数量。 每对已经相邻的元素都贡献零成本，每对不相邻的元素至少迫使其两个元素之一移动。 

因此，问题简化为计算初始网格中有多少对已经相邻。 如果一对已经位于相邻的单元格上，我们可以保留它并支付零费用。 否则，对于该对，我们必须移动至少一个端点，并且仅移动一个端点总是足够的：我们可以将一个事件重新定位到另一个事件旁边，而不会干扰其他已经满足的对的正确性，因为我们只是固定端点，而不是强制全局结构。 

因此，答案只是给定网格中不相邻的对的数量。

 ## 算法演练

1. 扫描网格并记录每个数字两次出现的坐标。 这使我们能够在每个值的恒定时间内将每对重建为两个位置。 
2. 对于每个数字，检查其出现的两次是否在网格中相邻。 这是通过比较曼哈顿距离等于 1 来完成的。如果它们相邻，则该对已经满足条件并且不需要移动。 
3. 计算有多少对不相邻。 每对这样的对都贡献了一个所需的动作。 
4. 输出该计数作为必须移动的元素的最小数量。 

关键的推理步骤是，如果不移动至少一个端点，则无法固定不相邻的对，并且仅移动一个端点总是足够的，因为我们可以将其放置在其伙伴旁边，而不会与其他固定对发生冲突，因为每个数字都是独立的。 

### 为什么它有效

 每个数字恰好出现两次，因此数字对在身份上不会重叠，仅在网格空间中重叠。 这种独立性意味着我们可以单独对待每一对。 一对要么已经有效（相邻单元格），要么无效。 在无效情况下，操作的下限是每对一次移动，并且可以通过本地固定一个端点来实现此限制。 由于没有一对需要多次调整，因此对所有无效对求和即可得出全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

pos = {}

for i in range(n):
    row = list(map(int, input().split()))
    for j, x in enumerate(row):
        if x not in pos:
            pos[x] = []
        pos[x].append((i, j))

ans = 0

for x, (a, b) in pos.items():
    (i1, j1), (i2, j2) = a, b
    if abs(i1 - i2) + abs(j1 - j2) != 1:
        ans += 1

print(ans)
```该代码首先构建一个字典，将每个值映射到它的两个坐标。 这是安全的，因为该问题保证每个数字恰好出现两次。 

然后对每一对进行独立检查。 曼哈顿距离条件直接编码网格中的邻接关系。 任何不满足此条件的对都会为答案贡献一个。 

一个常见的错误是尝试模拟实际的移动或交换，这是不必要的，并且会导致对之间交互的错误处理。 成对的独立性确保计数是足够的。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m = map(int, input().split())
    pos = {}
    for i in range(n):
        row = list(map(int, input().split()))
        for j, x in enumerate(row):
            pos.setdefault(x, []).append((i, j))
    ans = 0
    for x, pts in pos.items():
        (i1, j1), (i2, j2) = pts
        if abs(i1 - i2) + abs(j1 - j2) != 1:
            ans += 1
    return str(ans)

 ## 边缘情况

 极端情况是所有对都已正确相邻。 对于像这样的输入`1 1 / 2 2`，每对的曼哈顿距离为 1，因此算法计算零次移动并正确输出 0。 

另一种情况是类似棋盘的排列，其中没有相同的数字相邻。 在这样的网格中，每对贡献 1，输出等于不同值的数量。 该算法通过独立检查每一对来直接处理这个问题，没有任何干扰。 

最后一个微妙的情况是当对在狭小的空间中交错时。 尽管从视觉上看，移动一对可能会影响另一对，但值的独立性保证了每个决策都是局部的，因此邻接计数仍然有效，无需模拟。
