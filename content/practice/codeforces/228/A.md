[CF 228A - 你的马蹄铁在另一只蹄上吗？](https://codeforces.com/problemset/problem/228/A)

 **评分：** 800
 **标签：** 实施
 **求解时间：** 1m 7s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 瓦莱拉正好有四个马蹄铁。 每个马蹄铁都有一个由整数表示的颜色。 为了聚会，他希望所有四个马蹄铁都有不同的颜色。 

如果他的一些马蹄铁颜色相同，他必须购买新颜色的替换马蹄铁。 由于商店出售任何颜色的马蹄铁，唯一的问题是他需要额外购买多少马蹄铁才能最终获得四种不同颜色的马蹄铁。 

输入由四个整数组成，代表他当前拥有的马蹄铁的颜色。 输出是一个整数，即必须购买的马蹄铁的最小数量。 

限制很小。 只有四个值，每种颜色可以大到$10^9$。 颜色值的大小并不重要，因为我们从不对它们执行算术运算。 我们只需要判断两种颜色是否相等即可。 只需四个数字，任何合理的算法都可以轻松满足时间和内存限制。 

错误的主要原因是错误地计算重复项。 

考虑输入：```
1 1 1 1
```正确答案是：```
3
```只有一种不同的颜色，因此必须更换三个马蹄铁。 计算重复对的粗心实现可能会产生更大的数字。 

考虑：```
1 2 3 4
```正确答案是：```
0
```所有颜色已经不同，所以不需要购买任何东西。 

考虑：```
5 5 7 8
```正确答案是：```
1
```有三种不同的颜色。 只需要一种额外的颜色。 

关键的观察是，答案仅取决于已经存在多少种不同的颜色。 

## 方法

 暴力方法会比较每对马蹄铁，并尝试手动计算重复的颜色。 由于马蹄铁只有四个，所以这实际上是可行的。 只有六对，所以工作是恒定的。 

这种方法的困难不在于性能，而在于正确性。 当一种颜色出现三到四次时，配对计数就会变得很尴尬，因为多个重复的配对仅对应于少数替换。 例如，用颜色`1 1 1 1`，有六对相等，但答案只有三对。 

更简单的观察是，每种不同的颜色都可以保留，并且共享现有颜色的每个额外的马蹄铁都必须更换。 如果有`k`四个马蹄铁的颜色不同，那么正好`4 - k`马蹄铁需要更换。 

集合在这里是一个自然的工具，因为集合自动仅存储不同的值。 通过将所有四种颜色插入到一个集合中，集合的大小立即告诉我们存在多少种独特的颜色。 

答案变成：```
4 - number_of_distinct_colors
```| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(4²) | O(1) | O(1) | 已接受 |
 | 最佳 | O(4) | O(4) | 已接受 |

 ## 算法演练

 1. 读取四个颜色值。 
2. 将所有四个值插入到一个集合中。 

该集仅保留唯一的颜色，自动删除重复项。 
3. 计算不同颜色的数量作为集合的大小。 
4. 从 4 中减去该值。 

每一种不同的颜色都可以保留，而每一个剩余的马蹄铁都必须更换。 
5. 打印结果。 

### 为什么它有效

 该套装包含四个马蹄铁中出现的每种颜色的副本。 如果设定的大小是`k`，那么有`k`无需修改即可使用的颜色。 由于 Valera 总共需要四种不同的颜色，所以剩下的`4 - k`马蹄铁必须更换新颜色。 购买次数越少越好，因为每个重复的马蹄铁都会缺少一种独特的颜色。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

colors = list(map(int, input().split()))
print(4 - len(set(colors)))
```该解决方案读取四个整数并将它们存储在一个列表中。 将列表转换为集合会删除所有重复的颜色。 该集合的大小是现有可用的不同颜色的数量。 

表达式`4 - len(set(colors))`直接计算有多少马蹄铁是重复的，因此必须更换。 

不存在棘手的边界条件。 最小可能的答案是`0`当所有四种颜色都不同时。 最大可能的答案是`3`当所有四种颜色都相同时。

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline
    colors = list(map(int, input().split()))
    print(4 - len(set(colors)))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("1 7 3 3\n") == "1\n", "sample 1"

# custom cases
assert run("1 2 3 4\n") == "0\n", "all distinct"
assert run("1 1 1 1\n") == "3\n", "all equal"
assert run("5 5 7 8\n") == "1\n", "one duplicate"
assert run("1000000000 1 1000000000 2\n") == "1\n", "large values"
assert run("9 9 8 8\n") == "2\n", "two duplicated colors"
```| 测试输入| 预期产出 | 它验证了什么 |

 |`1 2 3 4`|`0`| 无需购买 |
 |`1 1 1 1`|`3`| 最大替换次数 |
 |`5 5 7 8`|`1`| 单一重复颜色|

 ## 边缘情况

 考虑输入：```
1 1 1 1
```该集合变为`{1}`。 它的大小是`1`，所以算法计算`4 - 1 = 3`。 必须更换三个马蹄铁，因为只有一种不同的颜色存在。 

考虑输入：```
1 2 3 4
```该集合变为`{1, 2, 3, 4}`。 它的大小是`4`，所以答案是`4 - 4 = 0`。 每个马蹄铁都已经有独特的颜色。 

考虑输入：```
5 5 7 8
```该集合变为`{5, 7, 8}`。 它的大小是`3`，生产`4 - 3 = 1`。 只有一个马蹄铁复制现有的颜色。 

考虑输入：```
9 9 8 8
```该集合变为`{8, 9}`。 它的大小是`2`，生产`4 - 2 = 2`。 还需要两种不同的颜色。 该算法无需任何特殊逻辑即可处理多个重复的颜色组，因为集合大小捕获了所有必要的信息。
