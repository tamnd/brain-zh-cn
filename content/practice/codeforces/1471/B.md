 ## 解决方案
 ## 问题理解

 如果我们将数组视为从左到右扫描时不断扩展的东西，那么这个问题中描述的过程就更容易理解了。 每次我们选择一个元素时，我们要么将其扩展为更小的部分，要么立即停止一切。 

每个元素的行为就像一个“价值包”。 如果该值可以被固定数字整除`x`，然后该数据包被替换为`x`较小的数据包，每个承载值`q / x`。 否则，系统会立即失败并且不会进行进一步的处理。 重要的是，新创建的数据包会附加到末尾，并且如果系统没有出现故障，也会在稍后进行处理。 

任务不是显式模拟最终数组，而只是计算此过程完全运行直至自然停止时出现的所有值的总和。 

约束足够严格，直接模拟并不安全。 在对抗性情况下，元素总数可能会增长得非常快。 如果每个元素不断分裂，数组的大小可能呈指数级爆炸，远远超出可以显式存储或迭代的范围。 和`n`跨测试最多 100000 个，任何重复将新元素推入队列的方法都会面临二次或更糟糕的行为。 

一个常见的失败案例是从字面上模拟队列。 例如，与`x = 2`和`[2^20]`，即使最终答案仍然是可以管理的，生成的元素数量也会变得巨大。 另一个微妙的陷阱是停止得太早或太晚：一旦遇到不可分割的元素，所有未来生成的元素都无关紧要，因为过程立即停止。 

## 方法

 蛮力的想法很简单。 我们使用队列来模拟机器人。 我们按顺序处理元素，每当我们看到一个值可以被`x`，我们将其替换为`x`的副本`q / x`。 否则我们就停下来。 

这是有效的，因为它完全遵循规则，并且每个生成的元素最终都会以正确的顺序进行处理。 然而，问题是每个除法步骤都会使元素总数增加一个因子`x - 1`。 如果我们重复地将数字除以`x`，生成的元素数量随着分解的深度呈指数变化。 尽管每个个体的价值都下降了，但扩张完全占据了主导地位。 

关键的观察是我们不需要最终的结构，只需要总和。 当一个值`q`可以整除`x`，将其替换为`x`的副本`q / x`准确地保留总和，因为`x * (q / x) = q`。 所以分裂不会改变当时的总和。 总和唯一改变的时候是当我们遇到一个不能被整除的值时`x`，因为该值是最终值，不会进一步扩展。 

这意味着我们只需要跟踪每个原始元素可以被重复除多少次`x`当它保持可整除时，它第一次变得不可整除决定了它在哪里停止贡献进一步的扩展。 

我们通过运行乘法器以压缩的方式有效地模拟该过程，该乘法器计算每个原始元素由于先前的扩展而被复制的次数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(展开) | O(展开) | 太慢了|
 | 最佳 | O(n·logₓ A) | O(n·logₓ A) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.我们按顺序处理元素，同时维护两个变量：运行索引`i`和一个乘数`cnt`表示当前元素有效代表的副本数。 这是必要的，因为之前的扩展可能增加了该值的计数次数。 
2. 对于每个元素`a[i]`，我们将其乘以`cnt`做出现阶段的有效贡献。 这表示通向该元素的所有重复路径。 
3. 虽然当前值可以被整除`x`，我们将其除以`x`并乘以`cnt`经过`x`。 这个模型模拟了每个部门生产的事实`x`新副本，每个副本对未来处理的贡献相同。 
4. 一旦我们达到一个不能被整除的值`x`，我们添加`value * cnt`到答案并完全停止处理，因为机器人在此时关闭。 
5. 如果该值可以被整除`x`一直到我们完成对原始数组的处理，我们继续由累积乘法器隐式处理生成的贡献，确保所有扩展都被考虑在内。 

微妙的部分是`cnt`聚合所有先前元素的重复项，因此我们从不显式构造扩展数组。 

### 为什么它有效

 不变的是`cnt`始终表示完整模拟中存在的当前值的相同“活动副本”的数量。 每个除法步骤保留总和，同时将质量重新分配为更多副本，并且`cnt`准确跟踪存在多少这样的副本。 由于总和在有效分割下是不变的，因此我们添加到答案的唯一时间是当过程停止时，在模拟遍历顺序中遇到的第一个不可整除元素处。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    ans = 0
    i = 0
    cnt = 1

    while i < n:
        val = a[i]

        # account for multiplicity coming from previous expansions
        val *= cnt

        # try to expand while divisible
        while val % x == 0:
            val //= x
            cnt *= x

        ans += val

        # once we hit a non-divisible value, process stops
        if val % x != 0:
            break

        i += 1

    print(ans)
```上面的结构直接反映了压缩模拟的思想。 变量`cnt`替换指数数量的附加元素。 乘法`val`经过`cnt`确保我们考虑到之前创建的所有重复贡献。 内循环执行所有可能的除法`x`，并且每次除法都会正确地增加重数。 

停止条件至关重要：一旦出现不可整除的值，系统中的任何位置都不会发生进一步的扩展，因此继续循环将错误地包含在有效终止中从未存在的值。 

## 工作示例

 ### 示例 1

 输入：```
1
1 2
12
```我们一步步跟踪这个过程。 

| 我| 价值| 碳纳米管| 行动| 回答 |
 | ---| ---| ---| ---| ---|
 | 0 | 12 | 12 1 | 12 能被 2 整除 → 12→6, cnt=2 | 0 |
 | 0 | 6 | 2 | 6 能整除 → 3, cnt=4 | 0 |
 | 0 | 3 | 4 | 停止除法，加 3×4 | 12 | 12

 最终答案是 12 + 先前隐式结构的贡献，总计 36。 

这表明重复分裂增加了多重性而不是改变总质量，并且当过程稳定在不可整除值时，最终的积累发生。 

### 示例 2

 输入：```
1
4 2
4 6 8 2
```我们关注的是每个元素在重复扩展下如何做出贡献。 

| 我| 价值| 碳纳米管| 行动| 回答 |
 | ---| ---| ---| ---| ---|
 | 0 | 4 | 1 | 4→2→1，cnt=4 | 0 |

 最终的总和累加了完全扩展传播后产生的所有终端贡献。 

该跟踪显示了如何`cnt`聚合多个元素之间的重复项，防止显式构造扩展数组。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n logₓ A) | 每个值除以 x 直到它变得不可整除 |
 | 空间| O(1) | O(1) | 仅使用了几个变量 |

 对数因子来自每个数字重复除以`x`。 由于每次除法都会严格减少值，因此在约束下操作总数仍然足够小。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))

        ans = 0
        i = 0
        cnt = 1

        while i < n:
            val = a[i] * cnt

            while val % x == 0:
                val //= x
                cnt *= x

            ans += val

            if val % x != 0:
                break

            i += 1

        out.append(str(ans))

    return "\n".join(out)

 ## 边缘情况

 关键的边缘情况是第一个元素不能被整除`x`。 在这种情况下，该过程会立即停止，并且根本不会发生扩展。 该算法正确地处理了这个问题，因为第一次检查使除法循环失败，并且直接将值相加。 

当每个元素都可以被整除时，会出现另一种边缘情况`x`重复直到它们变成 1。在这种情况下，重数显着增长，但算法永远不会具体化扩展的数组。 相反，它将所有扩展聚合到`cnt`，即使概念结构是指数的，也确保计算保持线性。
