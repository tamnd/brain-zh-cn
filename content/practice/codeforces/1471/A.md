 ## 解决方案
 ## 问题理解

 给定一个正整数序列，并且允许我们通过用它们的和替换它们来重复合并任意两个相邻元素。 每次合并都会将序列缩短一个元素，但保留所有原始值的总和。 

在以我们喜欢的任何方式完成合并后，我们使用评分规则评估结果序列：每个元素贡献其值的上限除以固定整数$x$，而总的美丽是这些贡献的总和。 

任务不是模拟所有可能的合并。 相反，我们必须确定所有合并策略的最小和最大可能的美感。 

约束允许最多$10^5$每个测试用例的数量和$10^3$测试用例，总计$10^5$要素整体。 任何尝试所有合并序列的解决方案都是不可能的，因为即使是局部选择也会以组合方式爆炸。 每个测试用例我们都需要一些线性的东西。 

一个关键的微妙之处在于，合并改变了值与上限函数交互的方式。 在保留金额的同时，$\lceil (a+b)/x \rceil$不等于$\lceil a/x \rceil + \lceil b/x \rceil$一般来说，合并的结构很重要。 

一个常见的失败案例来自于假设贪婪的本地合并总是有效。 例如，与$x = 3$，合并可以减少或增加上限贡献，具体取决于总和是否跨越多个$x$。 任何在不跟踪残留行为的情况下任意合并的方法都会在输入上失败，例如$4, 11$，其中：

 - 分开：$\lceil 4/3 \rceil + \lceil 11/3 \rceil = 2 + 4 = 6$- 合并：$\lceil 15/3 \rceil = 5$这个例子已经说明了为什么我们必须根据贡献而不是原始值进行推理。 

## 方法

 蛮力的想法是模拟每个可能的合并序列。 每次合并都会将数组大小减少一，并且在每一步中我们选择任何相邻的对。 对于大小的数组$n$，存在指数级数量的合并树，基本上都是序列上的二叉树。 即使计算结构，它也会像加泰罗尼亚数字一样增长，这使得它无法超越$n \approx 20$。 

障碍在于合并与上限函数非线性相互作用。 然而，如果我们将每个数字分成完整的大小块，则上限表现良好$x$和余数。 写作$$a_i = q_i x + r_i, \quad 0 \le r_i < x,$$我们观察到，无论分组如何，每个完整块对美感的贡献恰好为 1，因为$\lceil (qx)/x \rceil = q$。 困难完全在于剩下的部分。 

如果每个余数作为单独的组存在，则贡献 1，但如果多个余数的总和交叉，则可以组合成一个额外的完整块$x$。 因此，问题就变成了我们如何对余数进行分组，以最大化或最小化我们“溢出”到额外块中的次数。 

这将问题转化为将余数序列划分为连续的段，其中每个段贡献：$$\left\lceil \frac{\text{segment sum}}{x} \right\rceil.$$为了获得最大的美感，我们希望最大化产生溢出的段数。 当我们尽可能避免合并余数，并尽可能将它们分开时，就会发生这种情况。 为了最小化美观，我们希望有效地打包剩余部分，以便创建尽可能少的额外块。 

关键的简化是只有剩余部分对优化很重要； 商部分对所有元素贡献一个固定的常数和。

 ## 算法演练

 我们将每个数字分开$a_i$进入：

-$q_i = a_i // x$-$r_i = a_i \% x$总答案总是以$\sum q_i$，并且我们仅根据余数的分组方式进行调整。 

### 最大的美丽

 1. 计算$q_i$对于所有元素并将它们求和成一个基本答案。 
2. 独立处理每个元素的余数。 
3.添加$\sum \lceil r_i / x \rceil$，这只是非零余数的数量。 
4. 返回基数加上该计数。 

这样做的原因是，保持元素分离可以防止任何余数取消，从而最大化一个组跨越多个的频率$x$。 

###最低限度的美丽

 1. 计算相同的商基和。 
2. 提取所有余数。 
3. 按降序对余数进行排序。 
4. 将它们贪婪地打包成一个连续的段和。 
5. 每当运行总和达到或超过$x$，额外计数一个块并重置运行总和模数$x$。 
6. 最终答案是底数加上所形成的块的数量。 

排序步骤确保我们首先打包大量剩余部分，从而最大限度地减少稍后会导致额外交叉的碎片。 

### 为什么它有效

 不变的是每个元素贡献固定数量的完整$x$-块由其商确定，所有灵活性都在于剩余质量的分组方式。 任何有效的合并策略都完全对应于将剩余部分划分为连续的段。 为了最大化，我们避免组合余数，因此没有取消会降低段效率。 为了最小化，我们模拟将质量最佳地包装到尽可能少的段中，并且排序确保我们不会在小的剩余部分上浪费容量，而大的剩余部分可能会导致稍后不可避免的溢出。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))

        base = 0
        rem = []

        for v in a:
            base += v // x
            r = v % x
            if r:
                rem.append(r)

        # maximum: each non-zero remainder contributes 1 extra
        max_beauty = base + len(rem)

        # minimum: greedily pack remainders
        rem.sort(reverse=True)

        cur = 0
        add = 0
        for r in rem:
            if cur + r >= x:
                add += 1
                cur = 0
            else:
                cur += r

        min_beauty = base + add

        print(min_beauty, max_beauty)

if __name__ == "__main__":
    solve()
```该代码清楚地区分了商和余数贡献。 商部分立即累加，因为它在所有运算下都是不变的。 

对于最大计算，逻辑依赖于这样一个事实：如果保持隔离，任何非零余数都可以被迫提供额外的上限单位。 这可以避免任何可能减少交叉口数量的意外合并。 

为了最小化计算，将余数降序排序是必不可少的。 如果不进行排序，小的余数可能会首先被打包，而导致大的余数比必要的更频繁地溢出。

 | 初始| 3 | []| 当前=0，添加=0 | 3 |

```这证实了当不存在余数时，合并没有效果。 

### 示例 2

 输入：```
3 3

```我们计算：

 - 商：$2, 1, 3$所以基数 = 6
 - 余数：$0, 1, 2$| 步骤| 雷姆排序| 当前| 添加|
 | ---| ---| ---| ---|

 ## 边缘情况

 一个关键的边缘情况是每个元素都是以下的倍数$x$。 在这种情况下，所有余数都会消失，并且无论合并如何，答案都是固定的。 该算法自然地处理这个问题，因为余数列表变空，使得最大值和最小值都等于商之和。 

另一种边缘情况发生在$x = 1$。 每个元素都准确贡献其值作为上限计数，并且合并不会改变任何内容，因为$\lceil (a+b)/1 \rceil = a+b$。 该算法将所有内容简化为商累加，并再次产生相同的最小值和最大值。 

当余数都很小但总体超过时，会出现更微妙的情况$x$。 贪婪打包确保这些小块仍然累积到尽可能少的交叉中，并且排序步骤可以防止低价值元素过早消耗容量，从而迫使稍后产生额外的块。
