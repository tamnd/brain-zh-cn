 ## 解决方案
 ## 问题理解

 我们有一排单元格最初都未上漆。 我们将执行一系列绘制操作，其中每个操作绘制固定长度的连续段，但我们可以自由选择该段的起始位置。 每个操作都有自己的颜色，后面的操作会覆盖前面的操作。 

要求是所有操作完成后，必须对行中的每个单元格进行绘制，并且每种颜色必须在最终配置中至少出现一次。 挑战不是计算最终的着色，而是为每个片段构建有效的起始位置，以便这两个全局条件同时成立。 

关键的困难来自于以下事实：段可以任意重叠，并且后面的操作支配前面的操作。 这意味着早期的颜色是脆弱的：只有当我们在最终的排列中明确地为它们留出至少一个未覆盖的位置时，它们才能生存。 

这些约束允许最多十万个单元和操作，这排除了尝试所有布局或模拟所有配置的任何方法。 任何二次或偶数$O(n \log n)$每次操作构建速度太慢。 我们需要一个线性的构建策略来贪婪地确保可行性。 

当总覆盖范围不足或必须过早放置大段时，就会出现微妙的故障情况。 

例如，如果我们有一个长度为 1 的操作，但是$n = 2$，不可能覆盖所有单元格，因为一次操作只能绘制一个单元格。 当许多长段放置在短段之前时，会发生另一种失败情况，可能没有空间让短段放置其所需的可见颜色。 

## 方法

 蛮力的想法是尝试每个片段的所有可能的起始位置并模拟最终的绘画。 对于每个位置的选择，我们将计算每个单元格的最终颜色，并检查是否所有颜色都出现以及整个数组是否被覆盖。 由于每个段最多有$O(n)$选择，这大致导致$n^m$配置，即使对于小输入也是完全不可行的。 

一种更结构化的尝试是从左到右贪婪地模拟，始终尽早放置段。 然而，这忽略了保证每种颜色在最终配置中保持可见的需要。 始终从位置 1 开始的天真的贪婪也会失败，因为后面的段可能会覆盖所有出现的较早颜色。 

关键的观察是我们不需要动态地推理完全覆盖。 相反，我们可以根据保证的可见位置向后构建解决方案。 每个操作必须至少保留一个唯一的单元格，其颜色将保持最终颜色。 由于后面的操作会覆盖前面的操作，因此自然的策略是确保每个段至少引入一个新的未覆盖位置，并且以后不会被覆盖。 

这导致了一种建设性的策略：从左到右处理片段，同时确保在每一步我们仍然有足够的剩余长度来放置所有未来的片段，并为它们每个留下至少一个唯一的单元格。 

关键的限制是，如果我们将一个片段放置在右侧太远，我们可能会阻止未来的片段拟合。 如果我们将其放置得太靠左，我们可能会失去保证未来分段具有唯一可见单元的能力。 正确的结构通过维持每个段必须开始的移动下限来平衡这两者。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 太慢了|
 | 贪婪的建设性布局 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们按顺序处理段并维护一个指针`cur`表示当前段可以开始的最早位置，同时仍为所有剩余段留出足够的空间。 

1. 计算未来路段所需的总剩余长度。 最初这是所有长度的总和。 
2.对于第i段，确定最小可行起始位置。 如果我们将段放置在位置`p`，那么我们必须保证放置后，剩余的段仍然能够放入数组的后缀中。 这给出了一个约束：$$p \geq cur$$3. 还要确保段不超出数组边界：$$p \leq n - l_i + 1$$4. 我们选择最小的有效值`p`满足这两个约束条件。 这是最佳选择，因为较早放置不会损害后面段的可行性。 
5. 将线段 i 放置在位置 p 后，我们更新`cur`通过将其推进至少一个，确保未来的部分被迫占据新的区域，而不是崩溃到同一区域。 
6. 如果在任何时候有效范围变空，我们就断定构建是不可能的。 

### 为什么它有效

 该结构保持了这样的不变性：放置第 i 个段后，仍有足够的未使用容量来为每个剩余段分配至少一个新单元。 指针`cur`编码仍然允许所有后缀段可行的最早位置。 由于每个分段必须贡献至少一个可见单元，并且后面的分段会覆盖前面的分段，从而确保单调前进`cur`保证没有片段会失去出现在最终配置中的唯一机会。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
l = list(map(int, input().split()))

# total remaining length
remaining = sum(l)

# current minimum feasible start
cur = 1

ans = [0] * m

for i in range(m):
    remaining -= l[i]

    # earliest we can start so that future segments still fit
    min_start = cur
    max_start = n - l[i] + 1

    if min_start > max_start:
        print(-1)
        sys.exit()

    p = min_start
    ans[i] = p

    # move cur forward: ensure future uniqueness space
    cur = max(cur, p + 1)

print(*ans)
```代码维护一个运行下限`cur`为每个段的起始位置。 的价值`cur`每当我们放置一个段时都会增加，确保后面的段被迫占据新的位置。 上限检查确保我们永远不会将段放置在数组之外。 

一个微妙的细节是，我们只需要一个移动约束，因为后缀可行性是通过每个段始终消耗至少一个新位置来隐式保证的。 这避免了显式跟踪剩余的可用空间。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        n, m = map(int, input().split())
        l = list(map(int, input().split()))
        remaining = sum(l)
        cur = 1
        ans = []
        for i in range(m):
            remaining -= l[i]
            if cur > n - l[i] + 1:
                print(-1)
                return out.getvalue().strip()
            ans.append(cur)
            cur = max(cur, ans[-1] + 1)
        print(*ans)
    return out.getvalue().strip()

 ## 边缘情况

 当所有段的长度均为 1 时，就会出现临界边缘情况。在这种情况下，必须为每个单元分配一个不同的颜色位置。 该算法分配增加的起始位置，并且`cur`强制两个段不重叠。 用于输入`5 5`与所有人一起，星星变成了`1 2 3 4 5`，产生完全有效的着色。 

另一种边缘情况是长段在短段之前。 例如`5 2`有长度`5, 1`。 第一个段必须从 1 开始，因为它是唯一有效的位置。 在那之后，`cur`变为 2，强制第二段从 2 开始，这是有效的并确保短颜色出现在最终数组中。 

当任何段无法放置在给定当前的边界内时，就会出现失败情况`cur`。 例如，如果`cur`超越`n - l[i] + 1`，没有剩下合法的起始位置，并且构造正确地终止于`-1`。
