 **标签：** 二分查找，贪心
 **求解时间：** 2m 57s

 ## 解决方案
 ## 问题理解

 我们得到一个非常长的二进制字符串，仅包含字符 A 和 B，并保证第一个和最后一个字符始终是 A。除了这些固定端点之外，我们还得到了字符串中其他一些 A 字符的位置。 所有剩余位置均隐含 B.

 问题的结构完全由连续 A 字符之间的间隙决定。 如果我们按升序列出所有 A 位置（包括 0 和 n），则每个相邻对定义一个段长度。 所有相邻A对之间的最小线段长度是l，最大是r，我们关心的值是r减去l，它衡量这些间隙的不均匀程度。 

我们可以将 k 个 B 位置转换为 A 位置。 这样做之后，这些新的 A 位置将现有间隙分割成更小的间隙，从而可能改变最小和最大相邻距离。 目标是选择 k 个新的 A 位置，以使最大和最小差距之间的最终差异最小化。 

这些约束立即告诉我们什么样的解决方案是可能的。 测试用例总数非常大，高达 400,000 个，但所有测试的 m 总和也以 400,000 个为界。 这强烈表明任何解决方案都必须接近线性（以 m 为单位）进行摊销。 n 的值可以大到 10^15，因此我们无法迭代整个字符串，甚至无法显式表示它。 每个计算必须仅取决于 A 字符的位置，而不取决于 n 本身。 

一个天真的想法是明确模拟以所有可能的方式放置 k 个新 A，重新计算所有差距，并跟踪最佳平衡。 这是不可能的，因为即使是长度为 L 的单个间隙也有指数级的多种方法可以在其中放置 k 个插入。 即使将 k 点分布在多个间隙上也会导致组合爆炸。 

当贪婪地思考首先缩小最大差距时，会出现更微妙的失败案例。 这不一定有效，因为减少最大间隙可能会改变几次插入后哪个间隙成为新的最大值，并且这种相互作用使得局部贪婪策略在没有全局结构的情况下变得不可靠。 

关键的隐藏结构是，在一个段内插入 A 会将其分割成更小的段，并且最佳策略仅取决于我们为每个原始间隙分配多少分割，而不是插入的 A 的确切位置。 

## 方法

 首先查看原来的 A 位置。 他们将线划分为 m+1 个间隙。 每个长度为 d 的间隙贡献一个区间； 如果我们在其中插入 x 个新的 A，则该间隙将被分成 x+1 个较小的段。 

对于长度为 d 的单个间隙，如果我们以最佳方式分配 x 个插入，我们能实现的最好结果就是使段尽可能相等，因此最大结果段大约为 ceil(d / (x+1))，如果可整性允许，最小值为 Floor(d / (x+1))。 这表明，一旦我们决定每个间隙接收到多少插入，它就会独立地表现。 

暴力解决方案将尝试跨 m+1 个间隙的 k 个插入的所有分布。 对于每个分布，它将计算结果段长度并评估 r-l。 分布的数量大约是由 k 组成 m+1 个部分，在最坏的情况下，它是 k 的指数，这使得它不可行。 

关键的见解是我们不需要显式分配插入。 相反，我们可以反转观点：固定一个平衡度的候选答案x，并检查是否可以使用最多k次插入来实现r - l ≤ x。 这将问题变成了单调谓词的决策问题，这自然建议对答案进行二分搜索。

接下来的挑战是如何有效地检查可行性。 我们没有直接跟踪 r 和 l，而是观察到，为了使 r - l 变小，我们本质上是在尝试确保所有生成的段长度都落入某个紧密的区间内。 如果我们猜测目标最大允许片段长度，我们可以计算需要多少次插入来打破每个原始间隙，以便结果片段不会超过此阈值。 这为我们提供了每个间隙的独立成本函数。 

对于大小为 d 的间隙，如果我们希望所有段的长度最多为 L，则需要将其至少分成 ceil(d / L) 个片段，这意味着我们需要在该间隙中插入 ceil(d / L) - 1 次。 对所有间隙求和即可得出所需的插入总数。 如果超过 k，则候选 L 太小。 

这将可行性检查简化为跨越间隙的简单线性传递。 然后我们对可实现的最小 L 进行二分搜索。 一旦我们知道了 L，我们就可以推断出可能的最小 r-l，因为 l 就间隙的整数而言至少为 1，并且最优填充的结构确保了围绕 L 的段长度的紧密聚类。

 | ---| ---| ---| ---|
 | k 个插入的暴力分布 | 指数| O(米) | 太慢了|
 | 二分查找+贪心可行性检查| O(m log n) | O(米) | 已接受 |

 ## 算法演练

 我们将 A 位置视为边界并导出所有线段长度。 

1. 计算连续 A 位置之间的所有间隙长度，包括从 0 到第一个 A 以及最后一个 A 到 n 的边。 这将问题转换为独立线段长度的列表。 
2. 定义一个函数 check(L)，用于确定在插入至多 k 个新 A 后是否可以确保所有最终段的长度至多为 L。 对于长度为 d 的每个间隙，计算我们必须将其分成多少块，即 ceil(d / L)。 每个这样的分割需要比片段少插入一次。 
3. 对所有间隙所需的插入进行求和。 如果总和≤k，则L是可行的。 
4. 对 L 在 1 和 n 之间进行二分查找。 最小的可行 L 是段长度的最佳可实现上限。 
5. 找到 L 后，从概念上计算所得的段结构。 最佳分割后的最小可能段长度在每个间隙内尽可能平衡，并且全局最小值由间隙划分的均匀程度决定。 然后通过比较分割结构所暗示的最大和最小段大小来获得答案。 

二分搜索确保我们找到段大小的最严格的可能上限，而可行性函数确保 k 次插入足以强制执行该界限。 

### 为什么它有效

 一旦我们确定了最大允许的段长度 L，每个间隙都是独立的。一个间隙内插入 A 的任何配置都不会影响另一个间隙中需要多少个 A。 这种可分离性使得总成本跨越差距而增加。 谓词“我们能否使用 ≤ k 个插入来实现最大段长度 ≤ L”在 L 中是单调的，因为增加 L 只能减少或维持所需的分割。 单调性保证了二分查找的正确性。 最佳答案对应于可行的最小 L，因为任何较小的 L 都将严格要求比 k 允许的更多的分割，而任何较大的 L 根据定义都是次优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def feasible(L, gaps, k):
    need = 0
    for d in gaps:
        need += (d - 1) // L
        if need > k:
            return False
    return True

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        pos = list(map(int, input().split()))
        pos = [0] + pos + [n]

        gaps = []
        for i in range(len(pos) - 1):
            gaps.append(pos[i + 1] - pos[i])

        lo, hi = 1, n
        while lo < hi:
            mid = (lo + hi) // 2
            if feasible(mid, gaps, k):
                hi = mid
            else:
                lo = mid + 1

        L = lo

        # compute induced min and max segment lengths
        min_seg = 10**30
        max_seg = 0

        for d in gaps:
            parts = (d + L - 1) // L
            max_piece = (d + parts - 1) // parts
            min_piece = d // parts
            max_seg = max(max_seg, max_piece)
            min_seg = min(min_seg, min_piece)

        print(max_seg - min_seg)

if __name__ == "__main__":
    solve()
```代码首先重建 A 位置之间间隙的完整结构，因为只有这些间隙才重要。 可行性函数直接编码每个长度为 d 的间隙需要拆分为 ceil(d / L) 段的观察结果，这会转换为 (d - 1) // L 次插入。 

对 L（段长度的候选上限）执行二分搜索。 搜索是安全的，因为可行性是单调的：一旦值 L 起作用，任何更大的值也起作用。 

确定 L 后，代码会重建每个间隙的隐含分段。 每个间隙都被分成几乎相等的部分，大小最多相差一个。 最大段长度是所有间隙中最坏的情况，最小段长度是所有间隙中最好的情况，它们的差给出了最终答案。 

在计算所需的分割和段大小时，必须小心整数除法，因为 ceil 和 Floor 运算中的差一错误是此类问题中错误答案的最常见来源。

 ## 边缘情况

 一种微妙的情况是没有内部 A 位置。 整个结构是一个长度为n的单个间隙。 所有插入仅细分这一片段。 该算法将其视为单个间隙列表，可行性变为检查我们是否可以使用 k 个切割将 n 分成大小最多为 L 的块。 二分搜索正确地找到 n/(k+1) 附近的 L，并且重建产生几乎相等的段，因此 r-l 变得最小。 

另一种情况是 k 为零时。 那么就不可能进行分裂，答案完全由原来的间隙决定。 可行性函数立即拒绝所有小于最大初始间隙的 L，因此二分搜索返回该最大间隙，并且计算出的最小和最大段长度保持不变。 

第三种情况是当k非常大时。 那么每个间隙都可以几乎均匀地分割。 可行性函数接受非常小的 L 值，并且二分搜索收敛到可实现的最小均匀段大小。 每个间隙内的重建片段最多相差 1，因此 r-l 向零折叠，符合密集插入消除不平衡的直觉。
