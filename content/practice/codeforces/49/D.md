 ## 解决方案
 ## 问题理解

 游戏在一维的正方形条纹上进行，每个正方形都是黑色或白色。 Vasya 绘制初始配置，然后 Petya 可以执行移动以实现交替图案，其中没有两个相邻的方块共享相同的颜色。 移动包括选择任意两个连续的相同颜色的方块并任意重新绘制它们。 我们的目标是确定 Petya 达到交替状态所需的最小移动次数，如果不可能则报告 -1。 

输入由一个整数组成`n`表示条带长度，后跟一串`n`人物 （`0`对于白色，`1`对于黑色）代表初始颜色。 输出要么是实现交替的最小移动次数，要么是 -1（如果无法实现）。 

自从`n`最多可以达到 1000，复杂度为 O(n^2) 的算法是可以接受的，但任何更糟糕的算法都有超时的风险。 我们必须小心处理小的边缘情况，例如长度为 1 的条纹，它是简单交替的，或者颜色全部相同的条纹，这可能需要多次移动，或者如果方格数为奇数则不可能。 

一种简单的方法可能会尝试模拟每对可能的重绘动作，直到条纹交替为止。 对于大的情况这会失败`n`因为移动序列的数量呈指数增长。 一个常见的陷阱是假设交替模式总是可达的。 例如，条纹`1111`长度为4的可以转换为`1010`两步，但一条条纹`111`长度为 3 的方块无法实现交替状态，因为移动会影响两个连续的方块，而中心方块总是会发生冲突。 

## 方法

 蛮力方法将尝试所有两个正方形重新绘制的序列，直到条纹交替为止。 对于每对相同颜色的连续方块，我们将递归地尝试所有四个重绘选项并跟踪移动次数。 这是有效的，因为每次移动都会严格减少连续相同对的数量，但可能性的数量是指数级的`n`- 最坏情况下约为 4^(n-1) - 这显然是不可行的`n=1000`。 

优化的关键点是 Petya 的动作是局部的：他只影响两个连续的相同颜色的方块。 我们可以通过**连续相同方块的片段**来分析条纹，而不是模拟所有移动序列。 如果一个线段有长度`l`，然后将其分成交替的正方形，我们可以执行`floor(l/2)`移动。 每次移动都会将线段长度减少两倍，最终将线段分割成孤立的方块。 将所有段的总和得出最小移动次数。 

一个微妙之处在于奇数长度的线段仍然是可解析的，因为移动会影响对并在末尾留下一个方块，该方块可以自然地与其邻居交替。 唯一不可能的情况发生在片段长度为奇数并且整个条纹无法匹配交替图案时； 事实上，在一维中，每种配置最终都是可解的，因为任何单个孤立的正方形都已经相对于其邻居处于交替位置。 所以我们只需要计算每个段的移动次数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(4^(n-1)) | O(4^(n-1)) | O(n) 递归深度 | 太慢了 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.初始化一个计数器`moves = 0`跟踪重绘操作的​​数量。 
2. 从左到右扫描条纹，并将连续的相同方块分成片段。 保持连续计数`length`相同颜色的连续方块。 
3. 当一段结束时（当前方块与前一个方块不同），添加`length // 2`到`moves`。 重置`length = 1`对于新的细分市场。 
4.扫描后添加`length // 2`最后一段。 
5、输出`moves`。 

背后的原因`length // 2`是每次移动都会影响两个相同颜色的方块。 长度为2的线段需要移动1次，长度3也需要移动1次（剩下的方格会自然交替），长度4需要移动2次，以此类推。 

### 为什么它有效

 每次移动都会将一段连续的相同方块最多减少 2。 计数`floor(length/2)`移动确保每个片段都被分成不重复的方块。 因为我们独立处理每个最大分段，并且分段由交替颜色分隔，所以不需要进一步调整。 一维中不存在无法解析段的情况，因此我们永远不会产生错误的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
s = input().strip()

moves = 0
length = 1

for i in range(1, n):
    if s[i] == s[i-1]:
        length += 1
    else:
        moves += length // 2
        length = 1

moves += length // 2

print(moves)
```我们维护一个柜台`length`对于连续的正方形。 每次遇到不同的颜色时，我们都会计算前一段的移动。 最后一段在循环之后处理。 使用整数除法可确保奇数段仅正确计算必要的移动。 

## 工作示例

 **示例1：**输入`111010`| 我| s[i] | 长度| 移动|
 | --- | --- | --- | --- |
 | 1 | 1 | 2 | 0 |
 | 2 | 1 | 3 | 0 |
 | 3 | 0 | 1 | 1 (3//2) | 1 (3//2) |
 | 4 | 1 | 1 | 1 |
 | 5 | 0 | 1 | 1 |

 输出是`1`。 第一段`111`需要1步，其他人已经交替了。 

**示例2：**输入`1010`| 我| s[i] | 长度| 移动|
 | --- | --- | --- | --- |
 | 1 | 0 | 1 | 0 |
 | 2 | 1 | 1 | 0 |
 | 3 | 0 | 1 | 0 |

 输出是`0`。 不存在连续的相同方块，因此不需要移动。

 ## 边缘情况

 对于单个正方形`1`，算法正确返回`0`因为不需要移动。 

对于奇数长度的段，例如`11111`，算法计算`5 // 2 = 2`移动。 两次移动后，该段会分裂成交替的方块，并留下一个剩余的方块，这自然适合相邻的方块。 

用于交替输入`1010`，算法永远不会递增`moves`因为每个段的长度都是 1，所以确认它可以正确处理已经赢得的条纹。
