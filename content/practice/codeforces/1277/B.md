 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 在每个测试用例中，我们从一个正整数列表开始。 一次操作让我们选择一个值$c$，但前提是它是偶数，然后我们同时替换每个出现的$c$在数组中通过$c/2$。 

目标是尽可能少地重复此操作，直到数组中的每个数字都变为奇数。 

解释该过程的一个有用方法是，每个值通过重复除以二而独立演化，但关键限制是我们不能针对单个位置，我们只能同时影响所选偶数值的所有出现。 

约束允许最多$2 \cdot 10^5$所有测试用例的总数，因此任何试图在整个数组上逐步模拟每个操作或每个操作重复扫描数组的解决方案都不会通过。 解决方案必须基本上处理每个元素恒定的次数，或者将重复的结构压缩为每个测试用例的单遍。 

当许多数字在减半链期间共享重叠的中间值时，就会出现微妙的边缘情况。 例如，$40$和$20$互动是因为$40 \to 20 \to 10 \to 5$尽管$20 \to 10 \to 5$。 独立处理元素的简单方法会低估成本，因为它忽略了共享中间值仍然需要单独的操作，除非仔细考虑。 

## 方法

 一个蛮力的想法是直接模拟这个过程。 虽然数组中至少存在一个偶数值，但我们选择一些偶数$c$，除以所有出现的$c$乘以 2，然后重复，直到所有值都变为奇数。 每个步骤都需要扫描或维护值的频率图，以决定对哪个偶数进行操作。 在最坏的情况下，值如下$2^k$生成长的减半链，并且在转换后可能会重复出现多个不同的值。 这可能导致$O(n \log A)$操作，并且每个操作可能需要更新大型结构中的计数，这使得速度太慢。 

关键的观察结果是，每个数字在变成奇数之前都会产生一个偶数“链”。 对于一个号码$x$，我们可以重复除以二，直到它变成奇数，记录沿路径的所有中间偶数值。 例如，$40$生产链条$40, 20, 10$。 该链中的每个不同值代表在某个时刻所需的操作：必须对任何链中出现的每个不同偶数执行至少一个操作。 

现在关键结构变得可见：答案正是出现在数组的任何减半链中任何位置的不同偶数整数的数量。 每个这样的值必须至少选择一次，并且选择一次就足够了，因为该操作同时处理所有元素中该值的所有出现。 

这减少了收集所有数字的所有中间偶数值并计算唯一值的问题。

 ## 算法演练

 1. 对于每个测试用例，创建一个空集来存储与所需操作相对应的值。 该集合代表任何减半链中出现的所有偶数。 
2. 迭代数组中的每个数字。 
3. 当当前数字是偶数时，将其插入到集合中并将其除以二。 这模拟了数字的轨迹，直到它变成奇数。 每个插入都标志着我们将需要至少一个针对该值的操作。 
4. 对所有号码独立地继续此过程。 
5. 处理完所有元素后，集合的大小就是测试用例的答案。 

我们只记录偶数的原因是奇数已经是最终形式并且不需要运算。 

### 为什么它有效

 每个操作都以单个偶数为目标，并同时减少所有出现的偶数。 因此，在任何元素减半过程中的任何阶段出现的每个不同的偶数都必须至少消除一次。 相反，对每个不同的偶数值执行一次操作就足够了，因为一旦我们处理一个值$c$，所有出现的$c$立即成为$c/2$，而且我们永远不需要处理$c$再次。 这会在遇到的不同偶数值和所需的移动之间创建一对一的对应关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        seen = set()
        
        for x in a:
            while x % 2 == 0:
                seen.add(x)
                x //= 2
        
        print(len(seen))

if __name__ == "__main__":
    solve()
```该解决方案迭代每个数字并重复将其除以二，同时保持偶数。 每个中间偶数值都存储在一个集合中，因此数组中的重复值不会使答案膨胀。 最终结果只是遇到的唯一偶数值的数量。 

一个常见的错误是在值第一次出现时停止，或者对每个元素进行计数而不是全局计数。 这会多算或少算，因为多个元素可能共享相同的偶数祖先，并且每个这样的祖先对应于单个所需的操作。

 ## 边缘情况

 一个关键的边缘情况是数组仅包含奇数。 在这种情况下，循环永远不会执行，并且集合保持为空，从而正确地产生零操作。 

另一种情况是当所有数字都是 2 的幂时，例如$[1024]$。 链条就变成了$1024 \to 512 \to \dots \to 2$。 该算法收集每个中间偶数值，每个级别对应一个必要的操作。 这确保了答案等于输入中最大的二的幂的指数。 

最后，重复相同的值，例如$[6, 6, 6]$只贡献一条链$\{6, 3\}$。 由于 3 是奇数，因此只计算 6，并且该集合确保我们不会过多计算重复工作。
