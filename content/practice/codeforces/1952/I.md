 ## 解决方案
 ## 问题理解

 输入描述了一个算术式表达式，由整数和`+`操作员。 与标准算术的主要区别在于`+`并不意味着数字加法。 相反，每个操作都通过将两个数字视为二进制字符串并将它们缝合在一起来组合两个数字。 

具体来说，当我们看到这样的表达式时`a + b`，结果是通过采用二进制表示形式形成的`a`，附加二进制表示`b`紧随其后，并将生成的位串再次解释为二进制数。 输出是最终二进制字符串的十进制值。 

因此，任务不是通常意义上的求和，而是从左到右重复连接二进制表示并解释最终结果。 

约束含义源于每个操作操纵位长度而不是幅度的事实。 如果值可能很大或表达式包含许多运算符，则重复转换为字符串会太慢。 显式构建二进制字符串的简单方法可能会退化为二次行为，因为串联会重复复制不断增长的字符串。 

当涉及零时，会出现微妙的边缘情况。 零的二进制表示是`0`，不是空字符串。 这意味着与零连接仍然会增加长度至少一位。 例如，`1 + 0`变成二进制`"10"`，等于 2，而`0 + 1`变成`"01"`，等于 1。简单的整数加法方法完全忽略了这种结构不对称性。 

另一个极端情况来自长链操作。 例如，像这样的表达式`1 + 1 + 1 + 1 + ...`在正常的算术直觉下，它的值不会线性增长，但在这里它通过移位和附加位来增长，这会很快产生大量数字。 任何重复重建二进制字符串的解决方案都会超出时间限制。 

## 方法

 暴力解释评估每个`+`通过将两个操作数转换为二进制字符串，连接它们，然后转换回整数。 这是简单且正确的，因为它直接遵循操作的定义。 然而，如果中间结果增长到 k 位并且有 n 次操作，则每次串联的成本为 O(k)，并且 k 本身随着每一步而增长。 这会导致最坏情况下的总体 O(n²) 行为。 

关键的观察是二进制的串联可以使用位移位来模拟。 如果`b`二进制表示有 L 位，然后附加`b`到`a`相当于移位`a`左边 L 个位置并添加`b`。 这完全避免了字符串构造，并将其替换为每步的恒定时间算术运算（计算位长度除外）。 

可以使用内置运算有效地计算数字的位长度。 一旦我们知道每个操作数占用了多少位，我们就可以从左到右处理表达式并更新每个运算符的运行结果 O(1)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（字符串连接）| O(n²) | O(n) | 太慢了 |
 | 位长移位 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将表达式解析为由用 分隔的整数组成的标记`+`。 每个数字都是独立处理的，以便我们可以按顺序处理它。 
2. 用第一个数字初始化结果。 在发生任何串联之前，它充当起始二进制字符串。 
3. 对于每个下一个数字`b`，计算表示所需的位数`b`以二进制形式。 这决定了我们需要将当前结果移动多远。 
4. 将当前结果左移该位长度。 这在右端创建的空间恰好等于`b`以二进制形式。 
5. 添加`b`到移位后的结果。 这个地方`b`进入较低位，有效地连接其二进制表示。 
6. 继续此过程，直到表达式中的所有数字都被消耗完。 

### 为什么它有效

 在每一步中，当前值表示所有先前处理的数字的二进制串联。 左移下一个数字的精确位长度可确保没有位重叠，并且添加该数字将其精确地放置在新创建的较低段中。 这保持了运行结果始终是表达式前缀的正确二进制连接的不变性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def bit_length(x: int) -> int:
    if x == 0:
        return 1
    return x.bit_length()

def solve():
    s = input().strip()
    
    # split by '+'
    parts = s.split('+')
    nums = [int(p.strip()) for p in parts]
    
    res = nums[0]
    
    for b in nums[1:]:
        shift = bit_length(b)
        res = (res << shift) | b
    
    print(res)

if __name__ == "__main__":
    solve()
```解析步骤会删除空格并将表达式拆分为整数。 每个整数都直接从十进制输入转换而来。 核心转换使用左移下一个操作数的位长度，然后按位或，这相当于在这个非重叠位空间中进行加法。 

唯一微妙的实现细节是正确处理零。 它的位长度必须被视为 1，否则移位将无法保留其对最终二进制结构的贡献。 

## 工作示例

 ### 示例 1

 输入：```
1+1
```| 步骤| 当前结果（二进制）| 下一个号码 | 位长度| 运营| 新结果 |
 | ---| ---| ---| ---| ---| ---|
 | 1 | 1 | 1 | 1 | (1 << 1) + 1 | 11 | 11

 第一个数字开始二进制序列为`1`。 第二个数字`1`也有一位，所以我们左移一次并附加它。 最终的二进制字符串是`11`，等于十进制 3。 

这证实了该算法正确执行二进制连接而不是算术加法。 

### 示例 2

 输入：```
2+3
```| 步骤| 当前结果（二进制）| 下一个号码 | 位长度| 运营| 新结果 |
 | ---| ---| ---| ---| ---| ---|
 | 1 | 10 | 10 3 | 2 | (10 << 2) + 3 | 1011 | 1011

 数字 2 是`10`以二进制形式。 数字 3 是`11`，长度为 2。`10`剩下 2 给出`1000`，并添加`11`结果`1011`，十进制为 11。 

这显示了不同的位长度如何自然地确定移位量，从而保留正确的串联结构。

 ## 边缘情况

 一种边缘情况是零出现在表达式中的任何位置。 用于输入`1+0+1`，该算法将零视为一位值，因此序列在第二步中按移位 1 进行，从而保留结构。 最终结果与二进制串联规则一致，而不是跳过零。 

另一个边缘情况是小数字的长链，例如`1+1+1+...`。 每一步精确移动一位，因此结果会增长为左移二进制数，其中填充有 1。 该算法可以有效地处理这个问题，因为它从不构造中间字符串，仅通过移位和按位或运算更新整数。
