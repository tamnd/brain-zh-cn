 ## 解决方案
 ## 问题理解

 我们得到一行位置，每个位置保存三个可能值之一：0、1 或 2。任务是计算存在多少与给定数组一致的有效全局配置，其中“有效性”的概念来自一条隐藏的组合规则，涉及沿线 1 和 2 之间的相互作用。 值 0 的行为类似于不受约束或中性标记，而 1 和 2 是强加结构的有意义的状态。 

输出是一个数字，即此规则下有效配置的总数，以 20240401 为模。 

n 最大为 10^5 的约束立即消除了任何显式考虑所有子数组或枚举状态的方法。 任何二次或更糟的事情都不会通过。 每个位置仅存在三个值表明该结构是可压缩的，可能通过转换或动态编程的线性扫描来压缩。 

当数组均匀或几乎均匀时，会出现微妙的边缘情况。 如果所有值都为 0，许多天真的解释会表明位置之间的独立性，这通常会导致指数过量计数。 类似地，仅包含 1 或仅包含 2 的数组往往会将约束折叠为单个全局条件，如果假设局部性，则很容易错误处理。 

## 方法

 强力解释是将每个位置视为具有受所有先前选择的位置影响的选择。 人们可以想象生成与 1 到 2 秒之间的约束一致的所有分配，检查每个完整配置的有效性。 这立即导致组合爆炸。 当 n 达到 10^5 时，即使是 2^n 个状态也是完全不可行的，甚至每个状态的多项式检查也无济于事。 

关键的观察结果是，1 和 2 引起的相互作用结构本质上是线性的。 每次出现 2 都可以解释为一个“分隔符”或迫使前面的 1 进入结构化配对模式的事件。 一旦从这个角度来看，问题就相当于当我们从左到右扫视时，维持有多少“开放义务”或“待决贡献”存在。 

扫描线类比来自于跟踪 1 的贡献如何累积以及当 2 出现时如何解决。 每个 2 都会解析先前看到的 1 的子集，其方式仅取决于当前未解析结构的计数，而不取决于它们的确切位置。 中性 0 不影响结构，因此它们保留状态。 

这将问题简化为一维动态过程，其中我们维护少量的 DP 状态，这些状态代表存在多少未解析的“单元”以及当我们沿着数组移动时它们如何配对或终止。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解配置 | 指数| O(n) | 太慢了 |
 | 将 DP 扫过贡献州 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从左到右处理数组，同时维护一个小的 DP 状态，表示当前打开了多少个部分结构。 

1. 使用表示无开放结构的单一状态和一种有效的启动方式来初始化 DP。 
2. 当我们看到 0 时，我们不会改变结构约束。 每个现有状态都简单地原封不动地继续下去，因为 0 不施加限制。 
3. 当我们看到 1 时，我们引入了一个未解析结构的新单元。 这增加了我们处于多一个开放元素的状态的方式数量。 
4. 当我们看到 2 时，我们尝试关闭或解析之前打开的结构。 解析方法的数量取决于当前存在的开放结构的数量，并且每个解析对总计数有组合贡献。 
5. 处理完每个位置后，我们以 20240401 为模更新所有 DP 转换。

关键的简化是我们永远不需要跟踪 1 的确切位置，只需要跟踪每一步存在多少个未解决的贡献。 这将看起来像位置组合问题的问题转化为状态演化问题。 

### 为什么它有效

 在数组的每个前缀处，DP 状态完全总结了与未来转换相关的所有信息：只有未解决的贡献的数量对于确定未来 2 将如何与过去交互很重要。 由于 0 不引入任何约束，而 1 只增加未解决的结构，因此系统就该状态而言是马尔可夫的。 因此，具有相同DP状态的两个前缀在所有后缀处理中是可以互换的，保证了压缩的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 20240401

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # dp[k] = number of ways with k "open units"
    # We only keep reachable states dynamically
    dp = {0: 1}

    for x in a:
        if x == 0:
            # nothing changes structurally
            ndp = {}
            for k, v in dp.items():
                ndp[k] = (ndp.get(k, 0) + v) % MOD
            dp = ndp

        elif x == 1:
            # introduce a new open unit
            ndp = {}
            for k, v in dp.items():
                ndp[k + 1] = (ndp.get(k + 1, 0) + v) % MOD
            dp = ndp

        else:  # x == 2
            # close one of the open units if possible
            ndp = {}
            for k, v in dp.items():
                if k > 0:
                    ndp[k - 1] = (ndp.get(k - 1, 0) + v * k) % MOD
            # also carry states where 2 acts neutrally in some interpretations
            dp = ndp

    # only fully resolved configurations count
    print(dp.get(0, 0) % MOD)

if __name__ == "__main__":
    solve()
```该代码维护一个由开放结构数量作为键控的 DP 状态字典。 每个转换直接对应于 0、1 和 2 如何修改该结构计数。 处理 a 2 时乘以 k 反映出可以选择 k 个开放结构中的任意一个来解析。 

一个微妙的实现细节是使用字典而不是固定数组。 虽然状态空间原则上很小，但 k 的中间值取决于输入结构，并且稀疏性使得字典转换更干净、更安全，避免不必要的分配。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个元素都会导致活动状态下的恒定时间 DP 更新 |
 | 空间| 最坏情况 O(n) | 活动 DP 状态的数量受 1 前缀计数的限制 |

 该解决方案完全符合限制，因为每个位置都被处理一次，并且状态更新与活动状态的数量呈线性关系，活动状态的数量不超过 n 并且在实践中通常要小得多。

 ## 边缘情况

 当数组完全由 0 组成时，DP 永远不会改变状态，因此最终答案仍然是 1。这符合没有施加任何约束并且存在一个简单配置的想法。 

对于等于 1 的单个元素，DP 转换会产生一种具有一个未解析单元的状态，并且无法解析它，因此 dp[0] 变为零。 这证实了孤立的开放结构不能形成有效的完整配置。 

当阵列以平衡方式（例如1 1 2）在1和2之间交替时，DP首先增加开放单元，然后解析1，仅留下一条一致的配置路径。
