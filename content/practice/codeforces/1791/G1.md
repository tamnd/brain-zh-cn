 ## 解决方案
 ## 问题理解

 我们被放置在一条从 0 到 n 的整数点线上。 从 1 到 n 的每个位置 i 都有一个只能使用一次的传送器，使用它会将我们带回位置 0。在 i 处使用传送器的成本是 a[i]。 在使用传送器之间，我们可以沿着路线向左或向右行走，每一步花费 1 个硬币。 

我们从位置 0 开始，使用 c 个硬币，并希望最大化我们可以激活的不同传送器的数量。 每次传送后，我们都会回到 0，因此每次新的传送器尝试都会从相同的基本位置开始，但我们可能需要步行才能到达它。 

关键结构是，每次我们想要使用索引 i 处的传送器时，我们必须支付 i 个硬币从 0 走到 i，然后支付 a[i] 个硬币来激活它。 之后，我们返回到 0，并对剩余的传送器重复该过程。 

输入给出了多个测试用例，每个测试用例都有不同的行长度和预算。 我们必须根据每个测试用例独立计算预算内可以使用的传送器的最大数量。 

这些约束意味着跨测试用例的线性总输入大小，因此每个测试用例超过 O(n log n) 的任何解决方案都有 TLE 风险。 动态重新计算最佳选择或尝试所有子集的天真的尝试会立即爆炸，因为 n 总体上可以达到 2·10^5。 

如果假设选择最小的 a[i] 值始终是最佳的，则会出现一种微妙的故障模式。 这忽略了移动成本 i，即使 a[i] 很小时，移动成本 i 也可能占主导地位。 

例如，如果 c = 10 并且 a = [1, 1, 1, 100]，则最便宜的 a[i] 都相等，但由于移动成本 4，索引 4 实际上很昂贵，因此其实际成本为 104，这是不可用的。 纯粹对 a[i] 的贪婪会错误地选择它。 

当预算很大但 n 很小时，会出现另一种边缘情况：即使传送器成本为零，移动成本也会累积。 对于 a = [0, 0, 0, 0]，我们每次仍然支付 1+2+3+4，因此排序非常重要。 

## 方法

 直接的强力方法将尝试传送器的所有子集，并为每个子集决定使用顺序。 每个传送器的成本仅取决于其索引以及是否被选择。 即使我们通过增加索引或成本来确定顺序，我们仍然面临选择传送器的组合选择。 这会导致指数行为，大约为 O(2^n)，即使 n = 40 也是不可能的，更不用说 2·10^5 了。 

我们需要了解到底是什么决定了使用传送器的成本。 每个传送器 i 都会贡献一个等于 i + a[i] 的固定有效成本，因为每次成功的使用都从 0 开始，走到 i 并激活它。 除了我们必须选择不同的传送器并在这些独立成本上花费总预算之外，选择之间没有相互作用。 

一旦这样看，问题就变成了在类似背包的约束下，从权重数组 w[i] = i + a[i] 中选择尽可能多的项目，其中每个项目最多使用一次，并且我们希望最大化计数，而不是价值。 

为了在总和约束下最大化所选项目的数量，最佳策略始终是首先选择最小的权重。 这是一个经典的交换论点：如果我们选择较大的成本而跳过较小的成本，则交换它们可以提高可行性或保持不变而不减少数量。 

因此，我们计算所有 w[i]，对它们进行排序，然后贪婪地累加，直到预算用完。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 最优（排序+贪婪）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

1. 将每个传送器转换为其真实成本 w[i] = i + a[i]。 这代表一个完整使用周期的全部成本，包括旅行和激活。 
2. 将所有 w[i] 值收集到一个列表中。 每个代表一个独立的“项目”，我们最多可以选择一次。 
3. 按非降序对列表进行排序，以便我们首先考虑最便宜的传送器。 这种订购确保我们永远不会在昂贵的选择上浪费预算，同时还有更便宜的选择。 
4. 迭代排序后的成本，同时保持运行总和。 对于每个成本，如果添加它不超过 c，我们将其包括在内并增加我们的答案。 否则我们会提前停止，因为所有剩余成本至少同样大。 
5. 输出选中的传送器的数量。 

工作原理：每个传送器的成本结构都是独立的，目标是在单一预算约束下最大化数量。 任何选择更昂贵的传送器而忽略更便宜的传送器的解决方案都可以通过交换它们来改进，而不影响可行性。 这表明按成本排序并采用前缀是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        a = list(map(int, input().split()))
        
        costs = [a[i] + (i + 1) for i in range(n)]
        costs.sort()
        
        total = 0
        ans = 0
        
        for w in costs:
            if total + w <= c:
                total += w
                ans += 1
            else:
                break
        
        print(ans)

if __name__ == "__main__":
    solve()
```关键转换发生在每个成本计算为 a[i] + (i + 1) 的行中。 这将运动和激活编码为单个可比较的重量。 排序步骤至关重要，因为它强制执行贪婪结构； 如果不进行排序，局部决策将无法反映全局最优性。 

运行总和逻辑是标准的前缀累加。 早期的突破是安全的，因为一旦我们达到了无法适应的成本，由于排序，所有后续成本至少会一样大。 

## 工作示例

 我们从样本集中追踪两个案例。 

### 示例 1

 输入：

 n = 5, c = 6, a = [1, 1, 1, 1, 1]

 成本变为 w = [2,3,4,5,6]。 

排序已经是一样的了。 

| 步骤| 考虑成本| 运行总和| 使用传送器|
 | --- | --- | --- | --- |
 | 1 | 2 | 2 | 1 |
 | 2 | 3 | 5 | 2 |
 | 3 | 4 | 9 | 2（添加前停止）|

 我们停在第三个成本处，因为 5 + 4 超过 6。答案是 2，这意味着我们可以负担两个传送器。 

这表明即使所有 a[i] 都相同，贪婪者自然更喜欢较小索引的传送器，因为移动成本使它们不同。 

### 示例 2

 输入：

 n = 4, c = 5, a = [4, 3, 2, 1]

 成本变为 w = [5, 5, 5, 5]。 

| 步骤| 考虑成本| 运行总和 | 使用传送器|
 | --- | --- | --- | --- |
 | 1 | 5 | 5 | 1 |
 | 2 | 5 | 10 | 10 1（添加前停止）|

 我们只能使用一台传送器，因为任何第二次使用都已经超出了预算。 

此示例表明，即使 a[i] 减少，移动成本也会使所有选择相等，从而使计数纯粹受到预算限制。

 ## 边缘情况

 一种边缘情况是，a[i] 中的所有传送器都非常便宜，但位置很远。 对于 n = 3、c = 6、a = [0, 0, 0]，成本变为 [1, 2, 3]。 该算法采用所有三个，因为 1 + 2 + 3 = 6。忽略索引的幼稚策略会错误地假设所有索引都同样便宜，并且在其他分布中可能无法正确确定优先级。 

另一种情况是单个传送器价格便宜但距离较远。 对于 n = 3、c = 3、a = [100, 0, 0]，成本为 [101, 2, 3]。 正确答案是 1，因为只有索引 2 适合。 贪婪算法在排序后正确地首先选择了 2，这表明索引成本在转换中被完全捕获。 

最后的结构情况是预算几乎不允许最小的几个项目但不允许它们的组合。 排序前缀方法自然会处理这个问题，因为一旦累积和超过 c，我们会立即停止，确保不会出现无效的过度计数。
