 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，可以是正数、负数或零，并且允许我们执行任意次数的单个操作：选择两个相邻元素并同时翻转它们的符号。 目标是在最佳应用这些操作后最大化所有数组元素的总和。 

输入由多个测试用例组成，每个测试用例都有一个长度$n$和一个数组$n$整数。 每个测试用例的输出是一个整数：任意数量允许的操作后可实现的最大总和。 

限制因素很重要：$n$最多可达 200,000，并且总和$n$所有测试用例不超过 200,000 个。 这排除了任何检查每个可能的对序列或盲目模拟操作的算法，因为这种强力方法可能具有指数复杂性。 每个元素可以大到$10^9$或小至$-10^9$，因此中间和必须使用 64 位整数处理。 

容易忽视的边缘情况包括所有负数均为奇数长度的数组。 例如，$[-1, -1, -1]$不能将所有元素翻转为正，因为每个操作都会影响两个元素。 这里的最佳总和是通过翻转前两个元素得到的$[1, 1, -1]$，总和为$1$。 另一个微妙的场景是带有零的数组：翻转负数和零可以将负数转换为正数，而不会损害零，从而增加总和。 

## 方法

 蛮力方法很简单：迭代所有相邻对，翻转它们的符号，计算总和，然后重复，直到无法改进为止。 虽然这在原则上是可行的，但可能的操作序列的数量呈指数增长。 为了$n = 2 \cdot 10^5$，即使考虑每对一次也已经$O(n)$每个操作，迭代直到收敛可能会导致数百万或数十亿次操作，这是远远不可行的。 

解锁更快解决方案的关键观察来自奇偶校验和绝对值。 翻转两个相邻元素可以保留它们的绝对值之和，但允许我们更改符号。 如果所有元素均为非负数，则总和最大。 如果有偶数个负元素，我们可以将它们配对并翻转每一对，直到所有元素都是正的。 如果存在奇数个负元素，则除了一个之外的所有元素都可以翻转为正，留下最小绝对值元素为负。 这是因为该操作只能成对翻转符号，因此无法消除单个剩余的负数。 

最佳方法简化为对所有元素的绝对值求和，如果负数的计数是奇数，则减去最小绝对值的两倍。 这确保我们只留下一个负面因素，并将影响降到最低。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化变量`total_sum`为零和`min_abs`到一个非常大的值。 还跟踪`neg_count`为零。 
2. 迭代数组的每个元素。 对于每个元素，将其绝对值添加到`total_sum`。 更新`min_abs`如果绝对值小于当前值`min_abs`。 增量`neg_count`如果该元素为负数。 
3.处理完所有元素后，检查奇偶性`neg_count`。 如果是奇数则减去两次`min_abs`从`total_sum`来解释不可避免的负面因素。 
4. 输出`total_sum`对于当前的测试用例。 对所有测试用例重复此操作。 

为什么有效：绝对值之和代表所有元素都可以为正时可实现的最大值。 运算允许成对翻转，因此只有奇数个负数才能防止全部为正数。 减去最小绝对值的两倍模拟留下一个影响最小的负元素，从而产生最大的总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def max_sum_after_flips():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total_sum = 0
        min_abs = float('inf')
        neg_count = 0

        for x in a:
            if x < 0:
                neg_count += 1
            abs_x = abs(x)
            total_sum += abs_x
            if abs_x < min_abs:
                min_abs = abs_x

        if neg_count % 2 == 1:
            total_sum -= 2 * min_abs

        print(total_sum)

if __name__ == "__main__":
    max_sum_after_flips()
```代码直接反映了算法。 我们计算`total_sum`作为绝对值的总和。`neg_count`跟踪有多少个元素是负数，以及`min_abs`找到最小的绝对值。 支票为`neg_count % 2 == 1`确保我们考虑到无法消除一种负面因素的情况。 使用`float('inf')`比较是安全的，并且`abs()`正确处理大整数。

 ## 边缘情况

 在第一个边缘情况下$[-1, -1, -1]$，算法将绝对值求和为 3，计数 3 个负数，并减去 2 × 1 → 1。剩下的负数是不可避免的。 在第二种有零的边缘情况下，算法正确地将零视为非负数，并选择最小的绝对值作为零，从而避免减少总和。 在这两种情况下，算法都会产生正确的最大和。
