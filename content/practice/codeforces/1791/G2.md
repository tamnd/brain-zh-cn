[CF 1791G2 - 传送器（硬版）](https://codeforces.com/problemset/problem/1791/G2)

 **评级：** 1900
 **标签：** 二分查找，贪心，排序
 **求解时间：** 2m 13s
 **已验证：** 否

 ## 解决方案
 ## 问题理解

 我们得到一条数轴，其位置标记为 0 到 n+1。 位置 1 到 n 每个都有一个具有指定成本的传送器。 你从位置 0 开始，用 c 个硬币，可以用 1 个硬币向左或向右移动一个单位，或者在当前位置使用传送器立即到达线的任一端（位置 0 或 n+1），但需要支付传送器的费用。 一旦使用，传送器就无法重复使用。 目标是最大化您可以使用可用硬币使用的传送器数量。 

输入提供多个测试用例。 每个测试用例给出 n、传送器数量、c、总硬币和传送器数组成本 a[1..n]。 输出是每个测试用例使用的传送器的最大数量。 

约束意味着我们必须处理最多 2×10⁵ 的 n，并且测试用例中 n 的总和也是 2×10⁵。 迭代所有可能的传送序列的简单 O(n²) 方法会太慢。 每个测试用例我们必须保持在大约 O(n log n) 的范围内。 此外，硬币价值和传送器成本可以达到 10⁹，因此如果不小心，整数溢出是一个问题。 

不明显的边缘情况包括最便宜的传送器位于线路远端附近的情况。 例如，考虑 n = 4、c = 3、a = [5, 4, 3, 1]。 始终向右移动并按顺序尝试传送器的幼稚方法将无法选择索引 4 处的传送器，而索引 4 是可用的，因为移动 4 个单位的成本仅为 4，这刚好超出了预算。 微妙之处在于我们需要考虑从两端移动，因为在考虑移动成本时，在起点附近使用传送器比在末端使用传送器便宜。 

另一个边缘情况是所有传送器单独都太昂贵，例如 n = 3、c = 1、a = [2,2,2]。 正确答案是 0，但天真的实现可能会尝试第一个传送器，从而错误地计算硬币。 

## 方法

 暴力方法是尝试传送器的每种排列并计算总成本，包括它们之间的移动。 对于传送器的每个子集，我们会将到达它们的成本与传送器本身的成本相加。 每个测试用例的复杂度是 O(2ⁿ)，因为我们必须检查所有子集。 显然，当 n = 2×10⁵ 时，这会失败。 

关键的见解是观察到使用传送器的成本是传送器的成本加上从任一端（位置 0 或 n+1）到达它的最小移动成本。 对于传送器 i，有效成本为 min(a[i] + i, a[i] + (n - i + 1))，因为从 0 移动 i 个单位或从 n+1 移动 n - i + 1 个单位。 一旦我们预先计算了这些有效成本，问题就减少为在总硬币预算下选择尽可能多的传送器。 这是经典的“预算内项目数量最大化”问题。 

按升序对有效成本进行排序并迭代使用传送器直到超出预算，给出 O(n log n) 解决方案。 排序确保我们始终首先选择最便宜的可用传送器，从而保证最佳解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2ⁿ) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个传送器 i（索引为 1），计算其有效成本。 这是`min(a[i] + i, a[i] + (n - i + 1))`。 第一项是从左端开始的成本，第二项是从右端开始的成本。 这说明了到达传送器的最便宜路径加上其成本。 
2. 按升序对有效成本数组进行排序。 排序确保我们首先考虑最便宜的传送器，从而最大限度地提高我们能负担得起的数量。 
3. 初始化已用传送器的计数器和跟踪剩余硬币的变量，从 c 个硬币开始。 
4. 迭代排序后的有效成本。 对于每个成本，检查它是否小于或等于剩余的硬币。 如果是，则从预算中减去它并增加计数器。 否则，停止迭代，因为所有剩余的传送器都更昂贵。 
5. 处理完所有传送器或耗尽预算后，计数器代表可用传送器的最大数量。 

为什么有效：通过预先计算最小到达成本和排序，我们保证每个选定的传送器都是最便宜的。 任何其他订单要么会更快超出预算，要么选择更少的传送器，因此贪婪的选择总是安全的。 该问题简化为预算有限的选择问题，其中局部最优选择（最便宜的下一个传送器）导致全局最优。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        a = list(map(int, input().split()))
        eff = [min(a[i] + i + 1, a[i] + n - i) for i in range(n)]
        eff.sort()
        count = 0
        remaining = c
        for cost in eff:
            if cost <= remaining:
                remaining -= cost
                count += 1
            else:
                break
        print(count)

if __name__ == "__main__":
    solve()
```第一行读取测试用例的数量。 对于每个测试用例，我们读取 n 和 c，然后读取传送器成本。 我们计算有效成本时考虑了左右移动。 排序是为贪婪选择做准备。 该循环从预算中减去每个选定的成本，直到我们用完硬币。 使用基于 1 的索引进行移动可以简化成本计算，以匹配数轴上的位置。 

## 工作示例

 ### 示例 1

 输入：n = 5，c = 6，a = [1, 1, 1, 1, 1]

 | 我| 一个[我] | 左成本 = a[i]+i | 右成本 = a[i]+n-i+1 | 有效 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 2 | 5 | 2 |
 | 2 | 1 | 3 | 4 | 3 |
 | 3 | 1 | 4 | 3 | 3 |
 | 4 | 1 | 5 | 2 | 2 |
 | 5 | 1 | 6 | 1 | 1 |

 有效排序：[1,2,2,3,3]

 取1→余5，数1

 取2→余3，数2

 拿2个→剩余1个→不能拿下3个

 答案 = 2

 这证实了贪婪选择与有效的成本工作。 

### 示例 2

 输入：n = 8，c = 32，a = [100,52,13,6,9,4,100,35]

 计算有效成本：

 [108, 57, 16, 9, 13, 9, 107, 42] → 排序 → [9,9,13,16,42,57,107,108]

 挑选直至金币耗尽：9→23 左，9→14 左，13→1 左→停止

 答案 = 3

 这表明使用有效成本从两端选择传送器可以尽早跳过昂贵的传送器。
