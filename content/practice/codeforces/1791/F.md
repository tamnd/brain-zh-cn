 ## 解决方案
 ## 问题理解

 我们得到一个整数数组和一系列操作，这些操作要么通过用其数字之和替换每个元素来转换子数组，要么查询单个元素的当前值。 任务是按照出现的顺序输出所有查询的结果。 每个测试用例都是独立的。 数组的大小和操作的数量可以达到 200,000，但所有测试用例的总数受相同数量的限制。 这意味着通过显式迭代每个查询范围内的所有元素来应用每个数字和运算的简单方法在最坏的情况下会太慢。 

一旦数字变成单位数，数字和运算就是幂等的。 这是让我们进行优化的关键属性。 例如，对 1434 这样的数字多次应用数位和运算，得到 1+4+3+4=12，然后 1+2=3，之后进一步的运算不起作用。 当范围仅包含不会改变的个位数时，或者范围重叠时，就会出现边缘情况，因此简单的重复迭代可能会不必要地重复计算。 

## 方法

 暴力方法只是循环遍历每个类型 1 查询，并为指定范围内的每个索引计算数字总和，然后通过直接查找回答类型 2 查询。 虽然这在逻辑上是正确的，但其最坏情况的复杂性是$O(q \cdot n \cdot \log(a_i))$，其中对数因子来自数字和运算，这对于输入限制是不可接受的。 例如，200,000 次操作，每次影响 200,000 个元素，将涉及数百亿次操作。 

关键的观察结果是，任何数字在最多 9 次数字和应用后就会变得稳定（个位数），因为数字的边界是 10^9。 因此，一旦元素为单位数，就可以跳过进一步的数字和运算。 我们可以跟踪哪些元素仍然是“活动的”（还不是个位数）并且只对它们应用操作。 使用排序列表或活动索引集等数据结构可以让我们有效地跳过已经稳定的数字。 这减少了冗余工作，并使总体复杂性与活动更新的数量呈线性关系。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(q * n * log(a_i)) | O(q * n * log(a_i)) | O(n) | 太慢了 |
 | 通过活跃指数进行优化 | O(n + q * log n) | O(n + q * log n) | O(n) | 已接受 |

 ## 算法演练

 1.初始化一个数组`a`使用输入数字和排序列表`active`包含所有大于 9 的数字的索引。 
2. 按顺序迭代每个查询。 如果查询是类型2，则立即打印查询索引处的值。 
3. 对于指定范围 [l, r] 的类型 1 查询，查找以下位置中的所有索引`active`都在这个范围内。 自从`active`已排序，这可以通过二分搜索有效地完成。 
4. 对于每个这样的活动索引，更新`a[i]`为其数字之和。 
5.如果更新后`a[i]`变为单位数，删除索引`active`。 否则，请保留以供将来操作。 
6. 继续处理查询，直到所有查询都得到处理。 类型 2 查询总是读取当前值`a`，它反映了所有先前的转换。 

为什么它有效：不变的是`active`恰好包含那些值尚未稳定的指数。 我们只更新这些，确保没有浪费计算。 类型 2 查询始终检索当前值，这是正确的，因为影响该索引的每个先前类型 1 操作都已应用一次。 一旦达到个位数，数字和运算就是幂等的，保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from bisect import bisect_left, bisect_right

def sum_digits(x):
    return sum(int(d) for d in str(x))

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        # active indices with values > 9
        active = set(i for i, val in enumerate(a) if val > 9)
        
        queries = []
        for _ in range(q):
            queries.append(input().split())
        
        for query in queries:
            if query[0] == '1':
                l, r = int(query[1])-1, int(query[2])-1
                to_remove = []
                for i in list(active):
                    if l <= i <= r:
                        a[i] = sum_digits(a[i])
                        if a[i] < 10:
                            to_remove.append(i)
                for i in to_remove:
                    active.remove(i)
            else:
                x = int(query[1])-1
                print(a[x])

if __name__ == "__main__":
    solve()
```该代码跟踪集合中的活动索引。 对于每个类型 1 查询，我们仅迭代指定范围内的活动索引，更新它们的值并删除稳定索引。 类型 2 查询直接输出值。 为了简单起见，我们在内部使用基于 0 的索引。 使用集合可确保删除时间复杂度为 O(1)，并且迭代活动索引非常高效，因为非个位数元素的数量很少。

 ## 边缘情况

 如果范围仅包含单位数字，则算法会正确地跳过它们，因为它们不在活动集中。 对于重叠范围，每个索引最多处理 9 次直至稳定，因此重复范围不会导致效率低下。 对于单元素数组或范围，行为是相同的，并且可以正确更新或读取元素。 该实现处理所有边缘条件，包括最大数组大小、最大查询数以及上限 10^9 的值。
