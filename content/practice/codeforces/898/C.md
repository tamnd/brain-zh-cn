 ## 解决方案

 ## 问题理解

 每条输入行描述一个人的联系人列表的一个快照。 一行以人名开头，后面是该行中写有多少个电话号码，然后是这些号码的数字字符串列表。 同一个人可能会出现在多行中，同一个人的同一电话号码可能会出现多次。 

任务是整合每个人的所有信息，并输出每个名字的干净电话号码列表。 清理有一个特定的规则：如果一个人有两个号码，并且一个是另一个的后缀，那么较短的后缀号码是多余的，应该删除。 直觉是，较短的数字可能代表没有区域代码的相同完整号码，因此如果同一个人的完整版本已经存在，则不应打印它。 

输出是一个唯一人员的列表，对于每个人来说，都是删除后缀冗余条目后的一组经过重复数据删除的电话号码。 顺序对于人或他们的数量并不重要。 

限制很小：总共最多 20 个条目，每个条目最多有 10 个号码，每个号码的长度最多为 10。这立即告诉我们，即使对所有电话号码进行二次检查也是完全安全的。 任何多达大约几百万个字符串操作的方法都可以在限制范围内轻松运行。 

主要的微妙情况来自后缀规则和重复处理。 一些有代表性的情况阐明了必须正确处理的内容。 

如果某人在单个条目中包含重复的数字，例如：

 输入：```
1
alex 3 123 123 45
```那么正确的解释是同一条目内的重复项仅计数一次。 正确的输出应将其视为`{123, 45}`before applying suffix logic.

 如果忽略后缀删除，则会出现另一个失败：

 输入：```
1
bob 2 123 00123
```这里`123`是一个后缀`00123`，所以只有`00123`应该保留。 一个简单的基于集合的解决方案，仅删除精确的重复项，会错误地保留两者。 

另一个边缘情况是跨条目累积：

 输入：```
2
sam 1 123
sam 1 00123
```即使数字分散在各个条目中，在应用后缀逻辑之前也必须将它们合并。 

## 方法

 解决该问题的直接方法是首先将每个人的所有记录合并到一个电话号码集合中，使用集合删除精确的重复项。 之后，我们检查同一个人的每对数字，并消除那些作为另一个数字后缀的数字。 

这种强力逻辑是正确的，因为它明确地强制执行定义：如果某个数字作为属于同一个人的任何其他数字的后缀出现，则该数字将被删除。 然而，对于合并后每个人的总数最多为 100 个（最坏情况 20 个条目 × 10 个数字），检查所有对会导致每个人进行大约 10,000 次比较。 每次比较都涉及检查长度不超过 10 的后缀相等性，该长度仍然很小，因此即使这个简单的解决方案在这些约束下实际上也是可以接受的。 唯一效率低下的是，它会在较短的字符串不可能包含较长的后缀关系的对之间进行冗余工作。 

解锁更清晰解决方案的观察结果是，后缀关系是定向的和局部的：对于每个数字，我们只需要知道是否存在以其结尾的严格更长的数字。 这避免了重复的配对推理，并将问题转化为每个人集合内的简单成员资格检查。 

因此，我们可以存储每个人的所有唯一号码，然后通过检查它们是否是同一组中任何其他号码的后缀来过滤它们。 因为长度最多为 10，所以检查后缀匹配的成本很低，并且完整的解决方案变得简单。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力配对检查 | O(N·k²·L) | O(N·k²·L) | O(N·k) | O(N·k) | 已接受但多余 |
 | 集合+后缀过滤| O(N·k²·L) | O(N·k²·L) | O(N·k) | O(N·k) | 已接受 |

 这里N是人数条目，k是合并后每人的最大数量，L是数字的最大长度。 

## 算法演练

 我们处理所有输入行并按姓名聚合电话号码，然后独立清理每个组。 

1. 按人名将所有条目和群组电话号码读入字典。 每个名称都映射到一个列表或一组数字。 

我们这样做是因为后缀关系只在单个人的集合中重要。 
2. 对于每个人，将所有数字插入一组，以删除来自同一行中重复条目或重复值的重复项。 

这确保我们不会浪费时间多次检查相同的字符串。 
3. 将集合转换为列表进行迭代。 对于此列表中的每个数字，检查同一集合中是否存在另一个数字，使其以当前数字结尾并且严格更长。 

这捕获了以下规则：如果存在更完整的版本，则应丢弃较短的后缀版本。 
4. 构建一个过滤后的数字列表，这些数字不是同一组中任何其他数字的后缀。 

推理是只应该保留后缀关系下的最大元素。 
5. 输出不同名称的数量，然后为每个名称打印名称、剩余数字的计数以及以任意顺序的数字本身。 

### 为什么它有效

 在每个人的集合中，我们有效地构建了一个偏序，其中如果一个数字有另一个数字作为后缀，则该数字被认为“更大”。 该算法准确地保留了那些不严格受此顺序中任何其他元素支配的元素。 任何作为另一个数字后缀的数字都一定会被删除，因为我们明确地针对所有候选数字进行测试。 任何幸存下来的数字都不能是集合中更长的数字的后缀，这完​​全符合要求。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    people = {}

    for _ in range(n):
        parts = input().split()
        name = parts[0]
        cnt = int(parts[1])
        nums = parts[2:2 + cnt]

        if name not in people:
            people[name] = set()
        for x in nums:
            people[name].add(x)

    result = []

    for name, nums in people.items():
        nums = list(nums)
        keep = []

        for i, x in enumerate(nums):
            ok = True
            for j, y in enumerate(nums):
                if i != j and y.endswith(x) and len(y) > len(x):
                    ok = False
                    break
            if ok:
                keep.append(x)

        result.append((name, keep))

    print(len(result))
    for name, nums in result:
        print(name, len(nums), *nums)

if __name__ == "__main__":
    solve()
```第一阶段构建一个从名称到字符串集的字典，它合并重复的条目和条目内的重复项。 这是至关重要的，因为后缀逻辑不得受到重复的相同字符串的影响。 

第二阶段独立地迭代每个人。 对于每个号码，我们扫描该人集合中的所有其他号码，并使用以下命令检查后缀包含情况`endswith`。 严格的长度检查可以防止将相同的数字视为与后缀相关。 

最后阶段以任意顺序打印结果，这符合问题要求。

 ## 边缘情况

 一种重要的边缘情况是相同的数字在同一条目内或跨条目多次出现。 集合转换会提前删除这些内容，因此它们不会干扰后缀比较。 例如，`x = "123"`出现三次仍表现为单个元素。 

另一种情况是前导零，其中`"00123"`和`"123"`是不同的字符串，但其中一个是另一个的后缀。 该算法正确地将它们视为不同的字符串，同时仍然应用基于字符结尾的后缀逻辑。 

最后一个微妙的情况是所有数字形成后缀链，例如`"1"`,`"01"`,`"001"`。 后缀检查逐步消除较短的后缀，只留下最长的表示，这与存在更完整版本时应忽略较短后缀形式的规则一致。
