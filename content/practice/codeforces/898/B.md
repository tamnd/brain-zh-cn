 ## 解决方案

 ## 问题理解

 我们有固定的预算和两种类型的项目，每种项目都有固定的成本。 任务是确定我们是否可以通过购买一定数量的第一类型物品和一定数量的第二类型物品来完全匹配预算，其中允许我们购买每种物品零个或更多。 

更具体地说，我们想知道是否存在两个非负整数，代表两种商品类型的数量，使得它们的价格的线性组合等于总预算。 如果存在这样的一对，我们必须输出一个有效的对； 否则，我们报告这是不可能的。 

由于限制，预算和价格最高可达1000万。 该大小排除了任何迭代所有可能的计数对的情况。 对可能数量的双重循环将导致粗略的结果$10^{14}$在最坏的情况下进行操作，远远超出任何合理的时间限制。 即使对一个项目的所有可能数量（最多 1000 万）进行一次循环也是临界值，但如果每个步骤都是 O(1)（这是解决方案所采用的方向），则可以通过。 

当其中一个商品的价格为 1 时，就会出现微妙的边缘情况。在这种情况下，答案总是肯定的，因为我们始终可以使用该商品调整余数。 另一种极端情况是两个价格都高于预算。 那么唯一可能的总和为零，所以答案立即是否定的，除非预算为零，这是由约束排除的。 

朴素推理的一个更有趣的失败案例是假设我们需要对称地尝试所有组合。 例如，与$n = 7, a = 2, b = 3$，尝试所有对就可以了。 但与$n = 10^7$,$a = 2$,$b = 3$，即使存在有效的解决方案，暴力破解也变得不可行。 

## 方法

 直接的方法是尝试第一项的所有可能的数字。 对于每一个选择$x$，我们计算剩余的钱$n - x \cdot a$并检查是否可以使用第二项形成。 这意味着检查余数是否为非负且可被整除$b$。 这种方法是正确的，因为它系统地探索一个变量的所有有效值，同时确定性地计算另一个变量。 

问题是范围$x$。 在最坏的情况下，$a = 1$， 所以$x$运行至$10^7$。 每次迭代的时间复杂度为 O(1)，但循环仍执行一千万次迭代。 这在 Python 中是可以接受的，但不会导致效率低下，更重要的是，它表明我们可以做得更好。 

关键的观察是我们不需要尝试所有的值$x$。 由于我们只关心是否存在有效的对，因此我们可以通过利用模块化结构来减少搜索空间。 等式$x \cdot a + y \cdot b = n$可以重新排列为$y = (n - x \cdot a) / b$。 而不是扫描全部$x$，我们只需要确保达到残差类别，其中$n - x \cdot a$可以被整除$b$。 

这导致了具有两个变量且没有超出非负性约束的线性丢番图问题的标准技巧：仅在一个维度上迭代直至从另一个系数导出的小界限。 自从增加$x$经过$b$改变表达式模数$b$，我们最多只需要测试$b$候选者，但我们可以通过迭代来进一步简化$n / a$，这仍然是安全且易于实施的。 

更有效的观点是交换角色，因此我们总是迭代两个成本中较小的一个。 这最多可以保证$10^7 / 1 = 10^7$最坏情况下的迭代次数，但通常要少得多。

 | 蛮力 | O(n / a) 最坏情况 O(10^7) | O(1) | O(1) | 可以接受但很紧|
 | 最佳 | O(min(n/a, n/b)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们假设我们尝试一个变量的值并直接计算另一个变量。 

1. 确保我们首先迭代成本较小的项目。 这减少了最坏情况下所需的迭代次数。 
2. 循环所有可能的计数$x$这样$x \cdot a \leq n$。 每个$x$代表购买那么多第一类物品。 
3. 对于每个$x$，计算购买这些物品后剩余的钱。 这是$rem = n - x \cdot a$。 如果这变为负数，则进一步的值$x$只会让它变得更加消极，所以我们停下来。 
4. 检查是否可以使用第二项精确地形成余数。 当且仅当$rem \% b = 0$。 
5. 如果可整除，计算$y = rem // b$并输出该对$(x, y)$。 这保证了总匹配的精确性。 
6. 如果无效$x$产生一个有效的$y$，输出NO。 

### 为什么它有效

 每个有效的解决方案都对应于某个值$x$在我们列举的范围内，因为任何解决方案都必须满足$x \cdot a \le n$。 对于每一个这样的$x$，值$y$如果存在则唯一确定。 既然我们用尽了所有可行的办法$x$，我们不能错过有效的分解$n$。 正确性取决于这样一个事实：一旦第一个变量固定，第二个变量就不是独立选择的。 它完全由方程确定。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = int(input())
b = int(input())

# iterate over smaller unit cost first for efficiency
if a > b:
    a, b = b, a

found = False

for x in range(n // a + 1):
    rem = n - x * a
    if rem < 0:
        break
    if rem % b == 0:
        y = rem // b
        print("YES")
        print(x, y)
        found = True
        break

if not found:
    print("NO")
```代码首先对问题进行标准化，以便我们迭代更便宜的项目，从而减少循环迭代。 这种交换不会改变正确性，因为我们只是重命名对称方程中的变量。 

循环边界`n // a + 1`确保我们只考虑可行值$x$。 余数检查确保我们不会尝试无效的分解。 可整性测试保证第二个变量是整数，这是问题所要求的。 

这里一个常见的错误是忘记交换`a`和`b`改变输出变量的含义。 交换后，打印的对对应于交换的角色，这是一致的，因为我们仍然返回有效的分解。

 ## 边缘情况

 当其中一个价格为 1 时，循环变得几乎微不足道。 用于输入$n = 100, a = 1, b = 999$，算法立即发现$x = 100$,$y = 0$。 每次迭代都会确定性地减少余数，因此不可能失败。 

例如，当两个价格都超出预算时$n = 5, a = 6, b = 7$，循环仅运行$x = 0$。 余数为 5，不能被任一成本整除，因此算法正确返回 NO。 

当两种价格以多种方式划分预算时，例如$n = 12, a = 3, b = 4$，算法在遇到第一个有效分解时停止。 如果$x = 0$，它发现$y = 3$; 否则存在其他解决方案，但正确性不依赖于唯一性。
