 ## 解决方案

 ## 问题理解

 我们得到一个数组$n$一堆，每堆都包含一定数量的糖果。 一次操作允许我们将一堆糖果增加或减少恰好一颗糖果。 我们的目标不是使值相等或单独优化它们，而是调整它们，使一半的堆包含完美的正方形，另一半包含非正方形。 

这里的完全平方数是指以下形式的数$k^2$对于某个整数$k \ge 0$。 每堆都可以独立改变，但每改变一个单位就需要移动一次。 关键的困难在于我们不是独立地选择每堆的值； 我们必须准确选择$n/2$一堆变成正方形，其余的必须被迫变成非正方形。 

约束条件允许$n$高达 200,000 且值高达$10^9$。 这立即排除了任何尝试模拟所有值的转换或在不进行预处理的情况下以繁重的方式独立重新计算每个桩的最短路径的方法。 任何解决方案都必须在预处理后将问题简化为近线性工作。 

一个天真的想法是独立对待每一堆，并贪婪地决定是否将其转换为正方形或非正方形。 这失败了，因为选择在全局范围内相互作用：将一堆变成正方形可能很便宜，但由于基数限制，我们仍然可能被迫将其分配给非正方形组。 

当一堆已经是正方形时，就会出现第二个微妙的问题。 如果我们贪婪地将其保留为正方形，我们稍后可能会发现太多的堆总共是正方形，迫使我们以高成本将一些正方形转换掉，即使早些时候我们假设它们会留下来。 

例如，考虑这样一种情况，其中除了少数遥远的数字之外，许多数字都已经是正方形。 贪婪的“修复最近的”策略可能会过早地过度分配方格分配，然后被迫支付大量成本来转换一些方格。 

问题从根本上来说是关于准确选择$n/2$两个标签中每一个的项目，其中每个项目的成本取决于我们为其分配的标签。 这是一个全局分配问题，不是每个元素独立的。 

## 方法

 如果我们忽略全局约束，每堆都有两个自然成本。 一是把它变成正方形的成本，也就是到最接近的完美正方形的距离。 另一个是把它变成非正方形的成本，这个比较微妙：如果它已经是非正方形，则成本为零；如果它已经是非正方形，则成本为零； 如果它是一个正方形，我们必须将其移动到最近的非正方形整数，该整数在两个方向上距最近的正方形边界都是一个单位，从而给出一个小的恒定成本邻域。 

蛮力策略会尝试所有方法来选择$n/2$堆成正方形。 有$\binom{n}{n/2}$这样的选择，即使对于小公司来说也是完全不可行的。$n$。 即使我们尝试对所选方块的前缀和计数进行动态规划，我们仍然会处理$O(n^2)$州。 

关键的观察是，每一堆独立地贡献两种可能的成本，我们只需要准确选择$n/2$某一类别的项目。 这是一个经典的“精确挑选 k 个项目，最小化成本差异”的结构。 

我们为每一堆计算两个值：使其成为正方形的成本和使其成为非正方形的成本。 最初，假设所有桩都分配给更便宜或任意的基线类别，例如非方形，并计算将一堆切换为方形状态的“额外成本”。 然后任务就减少到精确选择$n/2$堆积成正方形，其中每个选择的增量成本等于“正方形成本减去非正方形成本”。 

对这些增量进行排序给出了最佳分配：我们选择$n/2$最小的三角形变成正方形。 这是一个标准的交换参数：如果选定的元素比未选择的元素具有更大的增量，则交换会减少总成本，同时保留计数约束。

 ## 算法演练

 1. 对于每堆值$a_i$，计算最接近的完全平方值。 使其成为正方形的成本是与最接近的正方形的绝对差。 这是可行的，因为任何平方值都必须位于整数之间$k^2$，以及最近的这样的$k^2$最小化绝对调整成本。 
2. 计算使该堆成为非正方形的成本。 如果$a_i$已经不是一个正方形，这个成本是0。如果它是一个正方形，我们必须将它移到最接近的非正方形整数，这是1个操作（要么$a_i-1$或者$a_i+1$总是非平方的$a_i > 0$）。 
3. 对于每一堆，计算一个增量值：$$d_i = \text{cost to make square} - \text{cost to make non-square}.$$这代表将这堆分配给正方形组而不是非正方形组要昂贵多少。 
4.全部排序$d_i$值按递增顺序排列。 
5. 准确选择$n/2$最小的桩$d_i$并将它们分配为正方形。 所有其他的都被指定为非正方形。 
6. 最终答案是：

 使所有桩变成非方形的基本成本，加上所选桩的增量$n/2$桩。 

第 6 步之所以有效，是因为我们将问题重新解释为从统一分配（全部非方形）开始，然后支付额外费用将选定的桩升级为方形状态。 

### 为什么它有效

 每堆都有两个具有固定成本的有效“状态”。 任何有效的最终配置都对应于选择大小的子集$n/2$分配给正方形状态。 总成本与选择成线性关系，因此它分解为基本成本加上独立的每项调整。 

排序参数确保了最优性，因为所选项目和未选择项目之间的任何反转都意味着在保持约束的同时减少或保留成本的交换。 重复应用此交换会导致排序选择达到最佳，这是用于具有独立权重的固定大小子集选择的标准拟阵式贪婪属性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_square(x: int) -> bool:
    if x < 0:
        return False
    r = int(x ** 0.5)
    return r * r == x or (r + 1) * (r + 1) == x

def closest_square_cost(x: int) -> int:
    r = int(x ** 0.5)
    best = abs(x - r * r)
    best = min(best, abs(x - (r + 1) * (r + 1)))
    if r > 0:
        best = min(best, abs(x - (r - 1) * (r - 1)))
    return best

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    deltas = []
    base = 0

    for x in a:
        sq_cost = closest_square_cost(x)

        if is_square(x):
            non_sq_cost = 1
        else:
            non_sq_cost = 0

        base += non_sq_cost
        deltas.append(sq_cost - non_sq_cost)

    deltas.sort()
    ans = base + sum(deltas[:n // 2])
    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先根据每堆到最近正方形的距离对其进行分类。 计算最近平方成本的函数显式检查相邻平方根，因为最近平方必须位于$\lfloor \sqrt{x} \rfloor^2$,$(\lfloor \sqrt{x} \rfloor + 1)^2$，或有时向下舍入较大时的前一个方格。 

然后，假设所有桩都变成非正方形，我们计算基线。 这很重要，因为非平方转换要么免费，要么只花费 1，这简化了簿记。 

增量数组编码将一堆切换到方形类别的成本有多大。 排序可确保$n/2$采取最有利的转换。 

一个微妙的实现细节是对零的处理。 零是一个完美的平方，将其转换为非平方仍然需要 1，因为最接近的非平方是 1。

 ## 边缘情况

 一个关键的边缘情况是许多值已经是完美的平方。 例如，如果数组是`[0, 1, 4, 9]`，所有元素都从方形类别开始。 该算法计算的增量反映了将每个元素保持为正方形与将其转换为非正方形的成本有多大。 因为我们必须只分配$n/2$正方形，恰好有两个元素将被强制进入非正方形组。 排序确保我们选择最不痛苦的转换，通常是最小的平方，如 0 和 1，因为转换它们是最便宜的。 

另一个微妙的情况是当没有元素是正方形时，例如`[2, 3, 5, 6]`。 在这里，所有非平方成本为零，而增量纯粹是达到平方的成本。 该算法选择两个最便宜的平方转换，这正确地最小化了总调整，同时仍然满足一半必须变成平方的要求。 

最后，值 0 很重要，因为它是一个完美的正方形，但表现得不对称：将其变成非正方形总是要花费 1，而使附近的数字变成正方形也可能会花费很小的值。 该算法可以正确处理它，因为两个成本函数都是显式计算的，而不是依赖于对称性假设。
