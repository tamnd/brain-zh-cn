 ## 解决方案

 ## 问题理解

 我们在圆形日线上从第 1 分钟到第 1e6 分钟给出了一组不同的时间点，其中每个时间点对应于在该分钟响起的闹钟。 警报仅在其确切的分钟起作用，而不是在任何时间间隔内起作用。 

关键条件是，如果存在 m 分钟的任何连续块，并且在该块内至少有 k 个闹钟开始响起，则 Vitalya 就会醒来。 仅计算其确切响铃分钟完全位于块内的警报。 

我们希望禁用尽可能少的警报，以便长度为 m 的间隔不包含 k 个或更多活动警报点。 

输入大小达到2·10^5个警报，而时间坐标达到10^6。 这立即排除了任何尝试显式检查每个可能间隔的方法，因为最多有 10^6 个可能的起始位置，并且每个间隔的简单计数会太慢。 

天真的解释可能会尝试在所有 m 长度的段上滑动窗口，并使用二分搜索或前缀和对每个段内的警报进行计数。 即使有前缀和，我们仍然需要评估大约 10^6 个窗口，这是边界但可以管理的，但是缺少的困难是我们可以删除警报，因此问题变成选择全局删除哪些点，而不是单独删除每个窗口。 

当警报聚集时，会出现微妙的故障情况。 

例如，如果所有警报都位于长度小于 m 的小区域内，则覆盖该区域的每个 m 窗口都会看到所有警报。 任何从单个窗口中删除的天真贪婪都可能会失败，因为窗口严重重叠。 

另一个边缘情况是均匀间距。 如果警报间隔开，使得每个窗口几乎不跨越 k 个点，则删除局部最优警报可能会同时减少多个窗口，因此局部决策很重要。 

## 方法

 暴力的想法是考虑每个可能的警报子集以删除并测试条件是否变为错误。 这是 n 的指数并且是不可能的。 

一种更结构化的暴力方法是固定一个候选窗口，计算有多少个警报落入其中，如果超过 k−1，则从该窗口中删除足够的点。 对所有窗口独立重复此操作是不正确的，因为删除会以不一致的方式影响重叠窗口。 即使我们尝试贪婪地逐个窗口地模拟，每次检查的成本也为 O(n)，即 O(n·m) 或 O(n·10^6)，这太慢了。 

关键的观察是倒转视角。 我们不考虑违反约束的窗口，而是将警报视为“覆盖”许多窗口的元素。 位置 a 处的每个警报恰好参与包含 a 的 m 长度间隔。 如果我们对警报进行排序，则任何违规都会在长度为 m 的某个区间内本地确定。 

那么问题就变成了：我们需要保证在每个长度为m的区间内，最多保留k−1个点。 同样，任何可以被某个长度为 m 的间隔覆盖的 k 点组必须通过删除至少一个元素来破坏。 

现在我们移动到排序警报位置上的滑动窗口。 对于每个右端点，我们找到结束于该处的长度为 m 的区间中有多少个点。 如果它超过k−1，我们必须从中删除一些点。 为了最大限度地减少未来的损害，我们应该从窗口的右侧删除，因为这些点参与未来窗口的数量最多。 

这将问题转化为对具有移动窗口的排序数组的贪婪问题，始终通过从违规段的最右侧部分删除多余的点来强制执行约束。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解Windows | O(n·m) | O(n) | 太慢了 |
 | 贪心排序+滑动窗口| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 将所有闹钟时间按升序排列。 

排序是必要的，以便任何有效的 m 长度间隔都对应于此顺序的连续段。 
2. 维护两个指针 l 和 r，定义排序数组上的滑动窗口。 该窗口表示长度最多为 m−1 的范围内的所有警报（因为两个端点都包含在分钟索引中）。 
3. 对于从 0 到 n−1 的每个 r，扩大窗口并将 l 向前移动，同时差值 a[r] − a[l] ≥ m。 

这确保窗口始终表示长度严格小于 m+1 分钟的有效间隔，符合包含在长度为 m 的段中的条件。 
4. 如果当前窗口大小超过 k−1，则出现违规。 

令窗口大小为 s = r − l + 1。如果 s ≤ k−1，则继续。 
5. 当 s > k−1 时，删除位置 r（窗口中最右边的元素）处的警报，增加答案，并在概念上将其排除在将来的考虑之外。 然后相应减少r方参与。 

删除后，窗口会以最佳方式有效缩小，因为删除最新点会最大程度地减少未来的重叠。 
6. 继续，直到处理完所有位置。 

### 为什么它有效

 不变的是，处理每个位置 r 后，结束于 r 的有效窗口不包含超过 k−1 个活动警报。 任何违规都会通过从窗口当前最右边界删除一个点来立即处理。 由于所有窗口都是由按排序顺序的连续段定义的，因此任何可能违反的未来窗口都必须在某个步骤包含当前的违反间隔。 通过消除最右边的点，我们删除了未来参与度最大的元素，确保之前固定的窗口不会变得更难以修复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m, k = map(int, input().split())
a = list(map(int, input().split()))
a.sort()

ans = 0
l = 0

for r in range(n):
    while a[r] - a[l] >= m:
        l += 1

    while r - l + 1 >= k:
        ans += 1
        r -= 1  # conceptually remove a[r]
        while l <= r and a[r] - a[l] >= m:
            l += 1

print(ans)
```排序步骤确保窗口结构是线性的。 左指针保持了内部所有元素都满足 m 长度约束的不变式。 当窗口变得太大时，我们模拟删除最右边的元素。 循环内r的减量是表示删除的概念装置； 在生产实现中，在预处理的滑动结构中维护一个单独的“活动”数组或贪婪地处理删除通常会更干净。 关键是每次删除都会将答案精确地减少 1，并永久降低重叠区域的密度。 

更标准的实现避免改变 r ，而是使用类似双端队列的结构或通过跳过已删除的元素来显式跟踪删除，但贪婪逻辑保持不变。

 ## 边缘情况

 一种边缘情况是所有警报都位于小于 m 的范围内。 在这种情况下，覆盖该范围的每个窗口都会看到所有警报，因此我们必须将全局范围减少到最多 k−1。 该算法处理这个问题是因为初始窗口立即超过 k−1 并触发重复删除，直到满足大小约束。 

另一种边缘情况是当 k = 1 时。任何窗口中的任何单个警报都会导致违规，因此必须删除所有警报。 滑动窗口会重复检测 size ≥ 1 并删除每个元素，产生 n 个删除，与预期结果相符。 

当 m 非常大（接近 1e6）时，会出现最终的边缘情况。 然后所有警报都集中在一个窗口中，解决方案退化为全局选择 k−1 个幸存者，删除其余的。 贪婪仍然从最右端重复删除，直到不变量成立，恰好产生 n−(k−1) 次删除。
