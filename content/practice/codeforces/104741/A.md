 ## 解决方案
 ## 问题理解

 我们得到了多个独立的查询。 每个查询包含以相同的未知位置数字系统书写的三个数字，基数为$X$， 在哪里$X$是 2 到 16 之间的某个整数。 数字是用字符书写的`0-9`和`A-F`，因此它们最多可以表示 15 的值。 

对于每个查询，我们被告知，当用基数解释时，第一个数字加上第二个数字等于第三个数字$X$。 碱基本身是未知的，不同的查询可能对应不同的有效碱基。 我们的任务是恢复任何基地$X$这使得每个查询的相等性都是正确的。 

约束意味着最多$10^5$查询，因此必须以恒定或接近恒定的时间检查每个查询。 如果仔细限制的话，尝试使用每个基数独立的重复算术将字符串完全转换为大整数的解决方案仍然可以工作，但每个查询的数字长度的任何二次方在最坏的重复情况下都是有风险的。 

一个微妙的边缘情况来自无效数字。 如果一个数字包含像这样的数字`F`，那么任意基数$X \le 15$立即无效。 另一种失败模式是忽略进位传播：即使数字总和在本地匹配，缺少进位检查也可能错误地接受无效基数。 

例如，考虑这样的情况：$A = 1F$,$B = 1$， 和$S = 20$。 在基数 16 中这是有效的，但在基数 15 中它是无效的，因为数字`F`是不允许的。 仅在逐个字符转换后检查算术而不验证数字范围的简单方法将错误地接受这种情况。 

## 方法

 暴力破解的想法很简单：对于每个查询，尝试每个碱基$X$从 2 到 16，转换$A$,$B$， 和$S$转换为该基数的整数，并检查等式是否成立。 由于基础范围小且固定，这已经表明了可行性。 

然而，关键成本是转化。 如果我们通过对每个数字重复乘法和加法来转换数字，则每次转换是$O(L)$， 在哪里$L$是位数。 每个碱基执行此操作 3 次，得到$O(3L)$，通过 15 个碱基我们得到$O(45L)$每个查询。 和$10^5$查询，如果实现干净的话，这在 Python 中仍然没问题，但是我们可以通过避免重复的完全转换来做得更好。 

关键的观察是我们不需要完整的整数值。 我们只需要检查加法是否在给定的基数中成立。 可以通过进位模拟逐位验证，就像手动加法一样。 这避免了构造大整数，并将每次检查减少为对数字进行一次线性扫描。 

因此，最佳策略是尝试每个基数并使用带有进位传播的数字加法来验证方程。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（每个碱基完全转换）|$O(T \cdot 16 \cdot L)$|$O(1)$额外 | 已接受 |
 | 最佳（按数字进位检查）|$O(T \cdot 16 \cdot L)$|$O(1)$额外 | 已接受 |

 改进主要在于常数因子和记忆行为，而不是渐近复杂性，但它简化了正确性并避免了不必要的整数构造。 

## 算法演练

 我们独立处理每个查询。 对于固定查询，我们从其数字中确定最小的可能基数，然后测试最多 16 个的所有有效基数。 

1. 提取出现在的所有数字值$A$,$B$， 和$S$，并计算最大数字值。 基数必须严格大于该值，否则表示无效。 
2. 对于每个候选基地$X$从$\max\_digit + 1$到 16，尝试验证是否$A + B = S$保持在基地$X$。 
3. 要验证基数，请模拟从最低有效数字到最高有效数字的加法。 我们反转所有三个字符串，因此索引 0 对应于个位。 
4. 维护一个初始化为 0 的进位。在每个数字位置，计算相应数字的和$A$和$B$，加上进位，并与数字进行比较$S$模数$X$。 如果发生不匹配，请立即拒绝该碱基。 
5. 处理完所有数字后，确保剩余的进位与剩余的数字相匹配$S$。 如果一切一致，则接受该基数并输出。 

我们在第一个有效碱基处停止，因为任何有效答案都是可以接受的。 

### 为什么它有效

 该算法在基数下强制执行加法的精确数字级一致性$X$。 进位变量捕获所有跨数字依赖性，因此每个位置都在定义位置数字系统的相同算术规则下进行验证。 因为我们在唯一可行的范围内尝试所有可能的基础，所以完整性得到了保证，并且因为每个候选都使用精确的算术规则进行检查，所以保证了可靠性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def val(c):
    if '0' <= c <= '9':
        return ord(c) - ord('0')
    return ord(c) - ord('A') + 10

def ok(a, b, s, base):
    carry = 0
    i = len(a) - 1
    j = len(b) - 1
    k = len(s) - 1

    while k >= 0:
        av = val(a[i]) if i >= 0 else 0
        bv = val(b[j]) if j >= 0 else 0
        sv = val(s[k])

        total = av + bv + carry
        if total % base != sv:
            return False
        carry = total // base

        i -= 1
        j -= 1
        k -= 1

    while i >= 0 or j >= 0:
        av = val(a[i]) if i >= 0 else 0
        bv = val(b[j]) if j >= 0 else 0
        total = av + bv + carry
        carry = total // base
        if total % base != 0:
            return False
        i -= 1
        j -= 1

    return carry == 0

def solve():
    T = int(input())
    for _ in range(T):
        a, b, s = input().split()

        max_digit = 0
        for ch in a + b + s:
            max_digit = max(max_digit, val(ch))

        for base in range(max_digit + 1, 17):
            if ok(a, b, s, base):
                print(base)
                break

if __name__ == "__main__":
    solve()
```该解决方案首先将整个输入中的字符一致地转换为数字值。 这`ok`函数是核心验证器：它模拟从右到左的加法，同时通过模运算和进位传播强制实施基本约束。 当一个数字比另一个数字长时，第二个循环处理剩余的数字，确保不留下任何隐藏的贡献。 

一个常见的陷阱是忘记基数必须严格大于存在的每个数字。 该检查避免了无效碱基中不必要的模拟，并防止错误接受。

 ## 边缘情况

 一个微妙的情况是所有数字仅在基数 16 中有效，例如涉及`F`。 该算法正确地将最小基数设置为 16，并避免了对较小基数的不必要检查。 

用于输入`F 0 F`，最大数字为 15，因此仅测试基数 16。 进位模拟立即证实`F + 0 = F`，产生零进位和精确的数字匹配，因此输出为 16。 

另一种边缘情况是数字具有不同的长度。 为了`1 0 1`，第二个数字除了其个位数之外没有任何贡献，并且进位逻辑正确地将丢失的位置视为零。 该算法仍然会生成基数 2，无需特殊大小写，因为缺失的数字在位置算术中自然被建模为零。
