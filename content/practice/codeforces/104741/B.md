 ## 解决方案
 ## 问题理解

 我们得到一个带权无向图$N$地点和$M$道路。 两名玩家从节点开始$1$并想要到达节点$N$。 它们沿着图一步步移动，但移动受到限制：从当前节点开始，下一条选定的边必须位于到节点的某个最短路径上$N$。 换句话说，在每一步中，他们都被迫在距目的地的剩余距离方面保持最佳状态。 

该游戏是回合制的。 第一个玩家（小M）选择节点的第一步$1$，然后小我选择下一个，然后他们交替。 当他们已经处于节点时被迫“采取行动”的人$N$失去，意味着达到$N$游戏结束，刚到达的玩家不能再移动，但对手被认为没有移动，因此根据所描述的规则结构获胜。 

双方都发挥最佳，我们必须判断小M（首发）是否能强行获胜。 

约束允许最多$10^5$节点和$2 \cdot 10^5$每个测试用例的边数，最多 10 个测试用例。 这立即排除了所有路径上的任何二次或状态扩展方法。 任何解决方案在图形大小上都必须本质上是线性的或接近线性的，通常$O(M \log N)$或者$O(N + M)$。 

微妙的困难在于，尽管图可能包含循环，但“必须遵循最短路径”规则有效地将游戏限制为由到节点的最短距离引起的有向无环结构$N$。 

如果人们将其视为图上的一般游戏而不强制执行最短路径约束，就会出现天真的错误。 

例如，考虑一个三角形图，其中节点 1 连接到 2 和 3，并且都连接到 4（目的地），且权重相等。 幼稚的游戏求解器可能会考虑任意转换并错误评估循环或重复状态。 正确的行为完全忽略非最短转换。 

如果从节点计算最短距离，则会发生另一种失败情况$1$而不是节点$N$。 该游戏是由到目标的距离约束定义的，因此反转最短路径计算的根会导致不正确的允许移动。 

## 方法

 暴力解释会将游戏状态模拟为由当前节点及其轮到的节点对组成的对。 从每个状态，我们尝试所有有效的最短路径边，并递归地确定当前玩家是否可以强制获胜。 虽然逻辑上是正确的，但这探索了一个游戏图，其大小与最短路径子图中的边数成正比，并且在最坏的情况下，当每个步骤存在多个最短路径延续时，会退化为指数分支。 高达$10^5$节点，这是完全不可行的。 

关键的观察是“必须始终沿着最短路径移动到$N$”规则在很强的意义上消除了循环。如果我们计算$dist[u]$作为最短距离$u$到$N$，那么每个有效的移动都会严格减少$dist$。 这意味着游戏图变成了有向无环图，其中边从较大距离走向较小距离。 

一旦我们有了 DAG，问题就变成了一个标准的获胜状态 DP：如果一个位置至少有一次移动到了失败位置，则该位置获胜；如果所有移动都移动到获胜位置，则该位置失败。 由于边总是从较高距离到较低距离，因此我们可以按升序处理节点$dist$，从$N$不存在任何移动的地方。

 ## 算法演练

 我们将游戏转换为最短路径限制有向图，然后对其运行标准的获胜状态动态规划。 

1.计算每个节点到节点的最短距离$N$使用 Dijkstra 算法。 这告诉我们，对于每个节点，它距最佳行程下的目标有多远。 
2. 对于每个无向边$(u, v, w)$，确定是否可以用于有效的移动。 边缘可从$u$到$v$当且仅当$dist[u] = dist[v] + w$，并且类似地可以从$v$到$u$如果$dist[v] = dist[u] + w$。 这种方向性完全是由最短路径一致性引起的。 
3. 将每个节点视为一个游戏状态。 定义一个布尔值$dp[u]$意思是“轮到节点的玩家$u$可以强行取得胜利。”
 4. 初始化$dp[N] = False$，因为到达$N$表示没有有效的传出动作。 
5. 按递增对节点进行排序$dist[u]$。 这确保我们处理从最接近的状态$N$向外。 
6. 对于每个节点$u$按此顺序检查所有邻居$v$这样移动到$v$是有效的（它通过边缘权重精确地减少距离）。 如果至少存在一个这样的邻居$v$在哪里$dp[v] = False$，然后设置$dp[u] = True$，因为当前玩家可以迫使对手进入失败状态。 
7. 如果不存在这样的移动，则设置$dp[u] = False$。 
8. 答案是$dp[1]$，因为游戏从节点开始$1$。 

### 为什么它有效

 最短距离限制保证每次有效的移动都会严格减少$dist[u]$。 这会导致对状态的严格排序，从而防止游戏图中出现循环。 因此，每个状态仅依赖于严格较小的状态，因此处理节点不断增加$dist$order 确保所有转换在需要时已得到解决。 DP 递归是正确的，因为每个合法动作都被考虑一次，并且获胜条件与 DAG 上的标准正常游戏组合游戏逻辑相匹配。 

## Python 解决方案```python
import sys
import heapq
input = sys.stdin.readline

INF = 10**18

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v, w = map(int, input().split())
        g[u].append((v, w))
        g[v].append((u, w))

    dist = [INF] * (n + 1)
    dist[n] = 0
    pq = [(0, n)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in g[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    nodes = list(range(1, n + 1))
    nodes.sort(key=lambda x: dist[x])

    dp = [False] * (n + 1)
    dp[n] = False

    for u in nodes:
        if u == n:
            continue
        for v, w in g[u]:
            if dist[u] == dist[v] + w:
                if not dp[v]:
                    dp[u] = True
                    break

    print("Little M is the winner." if dp[1] else "Little I is the winner.")

t = int(input())
for _ in range(t):
    solve()
```第一阶段使用 Dijkstra 计算距目的地的最短距离。 这种逆转至关重要，因为走势的定义是“越来越接近$N$，”所以距离必须根于$N$。 

第二阶段使用条件隐式过滤边缘$dist[u] = dist[v] + w$。 这避免了显式构建有向图并保持内存线性。 

DP 循环依赖于距离递增顺序的处理节点，以便每个$dp[v]$在计算之前就已经知道$dp[u]$。 

一个常见的实现错误是忘记多条边可以满足最短路径条件； 都必须检查。 

## 工作示例

 ### 示例 1

 考虑一个简单的链：

 1 --(1)-- 2 --(1)-- 3

 有目的地$3$。 

距 3 的最短距离为：

 | 节点| 距离 |
 | ---| ---|
 | 3 | 0 |
 | 2 | 1 |
 | 1 | 2 |

 处理顺序：3、2、1。 

对于节点 2，它移动到 3，并且$dp[3] = False$， 所以$dp[2] = True$。 

对于节点 1，它移动到 2，但是$dp[2] = True$，所以它不能强行获胜，因此$dp[1] = False$。 

所以小M在这个配置上就输了。 

### 示例 2

 图：

 1 连接到 2 和 3，都连接到 4（目的地），所有权重均为 1。 

最短距离：

 | 节点| 距离 |
 | ---| ---|
 | 4 | 0 |
 | 2 | 1 |
 | 3 | 1 |
 | 1 | 2 |

 处理顺序：4、2、3、1。 

在节点 2 和 3 处，都可以到达 4，因此都是获胜状态。 

在节点 1，两次移动都进入获胜状态，因此$dp[1] = False$。 

这表明，如果所有最优分支都能为对手带来获胜位置，那么拥有多个最优分支并没有什么帮助。

 ## 边缘情况

 关键的边缘情况是当图包含来自节点的多个最短路径边缘，但只有其中一些导致丢失状态时。 DP 必须考虑所有这些优势； 在第一个有效边沿提前停止是不正确的。 该算法通过在决定 DP 值之前显式检查满足最短路径相等条件的每个邻居来正确处理此问题。 

另一个微妙的情况是图表包含原始形式的循环。 这些循环在实施距离约束后消失，因为任何有效的移动都必须严格减少距离$N$。 这确保了即使是高度循环的输入图在 DP 阶段也能像 DAG 一样运行，并且算法仍然是明确定义的。
