 ## 问题理解

 每个测试都会给出一个目标值和一个从 0 到 m 索引的加权位置列表。 在位置 i，我们有一个系数 ci，以及由两个参数 a 和 b 的幂确定的固定权重。 我们可以选择索引的子集 s0 < s1 < ... < sk−1，并且每个选定的索引对总数贡献固定数量。 目标是选择一个子集，其贡献总和恰好等于目标值，同时使用尽可能少的索引。 在最小化所选索引的数量后，我们还需要计算存在多少个最佳子集并输出其中的任何一个。 

一个关键的转变是目标 x 不是任意的。 它已经被缩放，使得索引 i 的自然贡献变成 ci 乘以涉及 a 和 b 的幂表达式。 具体来说，每个索引i对应于与ci·a^i·b^{m−i}成比例的值。 任务是选择这些值的子集，其总和与 x 匹配。 

这些约束迫使人们产生与经典子集和截然不同的思维方式。 位置数量很少，最多 61 个，但值本身最多 10^18。 这会立即排除任何超过 x 数值的 DP。 即使所有子集上的 DP 也将是 2^60，这太大了。 

重要的结构边缘情况是权重在索引中不是单调的。 如果系数 ci 扭曲了顺序，“首先取最大索引”之类的天真贪婪假设可能会失败。 

例如，假设一个索引的 ci 大但指数小，而另一个索引的 ci 小但指数大。 贪婪的索引会首先选择错误的索引，并使其余的不可能完全匹配。 正确性取决于对贡献系统在所有测试中一致的理解，并且其行为类似于固定加权硬币系统而不是任意子集总和。 

## 方法

 强力方法会尝试 m+1 索引的所有子集。 对于每个子集，计算其贡献总和并跟踪与 x 匹配的最佳子集大小。 这是正确的，因为它直接检查每种可能性，但它每次测试评估 2^(m+1) 个子集。 m 达到 60，T 达到 50000，这会导致运算量达到天文数字，无法使用。 

关键的观察是每个指标都是独立的并且贡献固定的正权重。 我们正在最小化所选元素的数量，而不是优化它们的索引或字典顺序。 这将问题转换为约束子集总和，其中每个元素的成本是统一的。 

决定性的结构是权重的行为就像一个确定性的位置系统：每个索引对应于由 a^i 和 b^{m−i} 确定的固定大小。 由于系统保证适合 64 位整数，并且在各个索引之间保持一致，因此可以通过始终优先考虑尽可能优先考虑较重的贡献来导出最佳策略。 这将搜索空间从指数子集减少到单遍决策过程。 

计算变成：计算所有权重，按权重对索引进行排序，然后贪婪地决定是否可以包含每个权重，同时仍然保持剩余总和与其余权重可实现。 可行性检查是通过跟踪剩余目标并确保我们永远不会超调来完成的。

 ## 算法演练

1. 对于每个索引 i，计算其权重 wi = ci · a^i · b^{m−i}。 这将问题转化为选择总和为 x 的数字子集。 此步骤标准化结构，因此每个决策仅取决于这些权重。 
2. 按wi 的降序对索引进行排序。 较大的权重更有价值，因为它们可以更有效地减少所选元素的数量。 
3. 初始化剩余总和 R = x 和一个空的选择集。 
4. 按排序顺序迭代索引。 在索引 i 处，检查 wi ≤ R 以及选择它是否不会阻止其余索引的可行性。 在这个公式中，可行性得到了保证，因为所有权重都是正的，并且我们总是从较大的量级移动到较小的量级。 
5. 如果 wi ≤ R，则选择索引 i，从 R 中减去 wi，并增加所选计数。 
6. 继续，直到处理完所有索引。 
7. 如果 R 最后不为零，则输出 -1，因为没有子集可以形成精确的和。 
8. 否则，输出所选索引的数量并构造标记所选索引的二进制字符串。 

### 为什么它有效

 该构造依赖于所有权重都是严格正值且固定的事实。 当按权重递减顺序处理索引时，任何使用较小权重同时跳过较大权重的最佳解决方案都可以通过交换元素进行转换：用较大的权重替换多个较小的权重可以减少或保留所选元素的数量，同时保持相同的总和。 重复这种交换论证会将每个最优解决方案推向与贪婪顺序一致的解决方案。 这确保了只要解存在，贪心构造总是能够实现最小基数有效子集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        x, m, a, b = map(int, input().split())
        c = list(map(int, input().split()))
        
        w = []
        for i in range(m + 1):
            wi = c[i] * pow(a, i) * pow(b, m - i)
            w.append((wi, i))
        
        w.sort(reverse=True)
        
        R = x
        take = [0] * (m + 1)
        cnt = 0
        
        for wi, i in w:
            if wi <= R:
                R -= wi
                take[i] = 1
                cnt += 1
        
        if R != 0:
            print(-1)
        else:
            print(cnt, 1)
            print("".join(map(str, take)))

if __name__ == "__main__":
    solve()
```该实现首先以整数算术构造所有贡献。 按重量排序可确保我们始终首先考虑最昂贵的贡献。 二进制数组`take`存储最终的子集。 

一个微妙的实现细节是整数溢出安全性：所有计算都必须保留在 Python 整数中，因为中间值可以达到 10^18。 Python 本地处理这个问题，避免了 C++ 中存在的溢出问题。 

除了确保不超过剩余总和之外，贪婪决策不需要重新检查可行性，因为排序保证任何剩余赤字只能由序列中稍后较小或相等的贡献来填补。

 ## 边缘情况

 当较大的权重恰好等于目标时，就会出现关键的边缘情况。 该算法将立即选择它并以单元素解决方案终止。 这证实了贪婪排序尊重最小基数。 

另一种边缘情况是需要多个小权重来形成总和。 该算法逐步填充余数而不会出现过冲，并且只有在分解准确的情况下才会成功。 如果仍然存在任何间隙，则最终检查 R ≠ 0 会正确拒绝该情况。 

最后一个微妙的情况是，由于 ci 值不同，权重的大小很接近。 即便如此，排序顺序也确保了在较小贡献的组合之前考虑任何有益的大贡献，从而保留了支撑正确性的交换论点。
