 ## 解决方案
 ## 问题理解

 我们正在使用重复的周日历，其中每一天都由周索引和从 1 到 7 的工作日索引来标识。时间一次向前移动一天，在一周的第 7 天之后，下一周开始。 

从一对坐标给出的当前时刻开始，我们及时向前移动，直到给定的考试时刻。 考试当天不可进行任何活动。 此间隔中的每隔一天都可能有用，但某些工作日始终保留用于训练。 这些训练工作日每周都会重复，并且在这些日子里，学生不能利用这一天进行复习。 

任务是统计从当天开始到考试日前结束的时间间隔中有多少天不是训练日。 

间隔可以很长，以周为单位，最多可达一千周，但结构高度规则，因为工作日周期是固定的，每 7 天重复一次。 这意味着直接的日常模拟是不必要的。 

一个微妙的点是边界的包容性。 当日可用，而考试日则不可用。 这会创建一个半开区间，从当前日期开始，到考试日期之前结束。 

当独立对待周并忘记工作日循环无缝地跨越周边界时，就会出现一个幼稚的错误。 例如，如果训练日是工作日 1、2、3，并且间隔从第一周第 6 天到第 2 周第 2 天，则工作日对齐很重要。 

另一种常见故障是在 1 个索引工作日和模算术之间转换时出现一个错误。 

约束意味着在最坏的情况下，每天迭代是可以接受的，即 1000 周乘以 7 天，大约 7000 个步骤，但预期的解决方案是使用算术计数的每个查询的恒定时间。 即使存在多个测试用例，每个测试的 O(7) 解决方案也足够了。 

## 方法

 一个简单的方法是模拟从开始到考试前一天的每一天。 对于每一天，我们计算其工作日并检查它是否属于训练集。 如果没有，我们就增加答案。 

这是可行的，因为间隔大小以几千天为界限，因此在一秒的约束下，所有天的循环都是安全的。 然而，这种方法在概念上变得低效，并且如果增加界限则无法扩展，更重要的是它隐藏了问题所依赖的周期性结构。 

关键的观察是工作日每 7 天重复一次，因此“火车或不火车”的模式是周期性的。 我们可以计算间隔内有多少个整周并乘以贡献，然后处理剩余的前缀和后缀段，而不是每天迭代。 

这将问题简化为计算一个范围内有多少整数落入模七的某些残差类别。 每个训练工作日恰好对应一个残差类别，因此我们将问题简化为对一段进行模块化计数。 

蛮力之所以有效，是因为输入大小很小，但它作为通用方法失败了，因为它忽略了周期性结构。 模块化算术视图将整个时间线压缩为每个残基的恒定时间计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n) 其中 n ≤ 7000 | O(1) | O(1) | 已接受但非最佳 |
 | 模块化计数| O(7) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 将开始日期和结束日期转换为单个线性索引。 将每天视为从 0 开始的整数，其中每周贡献 7 个连续索引。 这允许直接减法来计算间隔长度。 
2. 将间隔定义为从 L（含 L）到 R（不含 R）的所有整数日索引，其中 L 是开始日索引，R 是考试日索引。 这样可以避免重复计算考试日期。 
3. 将间隔中的总天数计算为 R 减去 L。这表示删除训练约束之前的所有候选天数。 
4. 通过从每个工作日值减一，将训练工作日转换为从零开始的余数模 7。 这会将工作日 1 与残基 0 对齐，将工作日 7 与残基 6 对齐。 
5. 对于每个训练残差，计算区间 [L, R) 中有多少个整数满足 i 模 7 等于该残差。 这是通过算术级数上的前缀计数来完成的。 
6. 从总间隔长度中减去所有训练日计数的总和，以获得可用的复习天数。 

关键的不变量是每个整数日索引恰好对应于一个工作日残差，并且天和残差之间的映射在整个时间线上是统一的。 由于这种一致性，计算片段上残基的出现次数可以完全捕获所有训练约束，而无需显式迭代。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_le(n, r):
    if n < 0:
        return 0
    q = n // 7
    rem = n % 7
    return q + (1 if rem >= r else 0)

def solve():
    x0, x1, x2 = map(int, input().split())
    a0, a1, b0, b1 = map(int, input().split())

    L = (a0 - 1) * 7 + (a1 - 1)
    R = (b0 - 1) * 7 + (b1 - 1)

    total = R - L

    blocked = 0
    for d in (x0, x1, x2):
        r = d - 1
        blocked += count_le(R - 1, r) - count_le(L - 1, r)

    print(total - blocked)

if __name__ == "__main__":
    solve()
```该解决方案将每个日期压缩为单个整数索引，以便时间进展变成线性算术。 函数 count_le 计算给定范围内有多少个数字落入特定的模类，这允许快速计数间隔内的所有训练工作日。 

使用 R 减一和 L 减一的减法可以正确强制半开区间。 一个常见的实施错误是忘记一致地移动两端，这会导致错误地包括或排除考试日。 

## 工作示例

 考虑训练天数为 1、3、5，间隔从第 1 周第 2 天到第 1 周第 7 天的情况。 

我们转换为线性索引：

 | 数量 | 价值|
 | --- | --- |
 | 左 | 1 |
 | 右 | 6 |
 | 总计 | 5 |

 我们现在计算每个残留物的阻塞天数。 

| 残留物 | 计数 (R-1) | 计数 (L-1) | 贡献 |
 | --- | --- | --- | --- |
 | 0 | 1 | 1 | 0 |
 | 2 | 1 | 0 | 1 |
 | 4 | 1 | 0 | 1 |

 阻塞等于 2，所以答案是 5 减 2 等于 3。 

这表明，即使间隔很小，残差计数也可以正确地仅隔离相关工作日，而无需显式迭代。 

现在考虑一个边界情况，其中间隔跨越一周边界。 设开始时间为第 1 周第 7 天，结束时间为第 2 周第 2 天，训练第 1 天。 

我们得到：

 | 数量 | 价值|
 | --- | --- |
 | 左 | 6 |
 | 右 | 8 |
 | 总计 | 2 |

 训练残差为 0。这两天中只有一天是工作日 1，因此阻塞等于 1，给出答案 1。这证实了跨周转换的正确处理。

 ## 边缘情况

 一种极端情况是间隔正好在训练日开始。 在这种情况下，起始日仍应计入阻止集中，并排除在修订日之外。 线性索引转换可以自然地处理这个问题，因为 L 包含在范围内。 

当间隔长度小于 7 天且跨越一周的时间时，会出现另一种边缘情况。 天真的全周乘法会超出训练天数，但基于残数的计数可以通过前缀算术正确处理部分片段。 

最后一个边缘情况是考试在第二天进行。 那么 R 等于 L 加一，答案是一或零，具体取决于这一天是否是训练日。 该公式正确归约，因为该区间恰好包含一个整数，并且残差检查直接捕获该整数。
