 ## 解决方案
 ## 问题理解

 我们获得了几台独立的评估机。 每台机器都有有限数量的线程，使用更多线程会以一种不平凡的方式改变运行时行为。 

对于第 i 台机器，有$k_i$可用线程。 如果我们准确地分配$j$任务分配给那台机器，然后每一个$j$任务随时间运行$t_{i,j}$。 顺序$t_{i,1}, t_{i,2}, \dots, t_{i,k_i}$是非递减的，这符合添加更多负载并不会使单个线程更快的直觉。 

现在我们有$M$代码提交总数。 每次提交都必须分配给某台机器，并且每台机器都会收到一个编号$a_i$提交的内容，其中$0 \le a_i \le k_i$和$\sum a_i = M$。 

在所有有效整数向量中统一选择分配$(a_1, \dots, a_N)$满足这些约束条件。 对于固定分配，总运行时间是机器的总和$a_i \cdot t_{i,a_i}$。 We need the expected value of this total sum modulo$10^9+7$。 

这些约束意味着最多有一个组合 DP$10^4$跨机器的总容量，最多$2 \cdot 10^3$机器。 对所有赋值的简单枚举需要对 M 的所有组合进行迭代，而这在 M 中呈指数增长，并且是不可能的。 

第二个天真的想法是，为每台机器独立计算其负载的预期贡献，但负载的分布$a_i$由于全局约束而不是独立的$\sum a_i = M$。 这种耦合是核心难点。 

当机器有容量时会出现微妙的边缘情况$k_i < M$。 任何有效的分配都必须尊重所有容量，因此许多机器可能在所有配置中都饱和。 朴素的多项式假设会错误地允许无效状态并过度计算概率质量。 

## 方法

 直接的方法是枚举所有有效向量$(a_1, \dots, a_N)$。 对于每台机器，我们选择一个值$0$到$k_i$，并且我们强制执行总和约束。 即使是对机器和总负载的动态编程也会导致状态空间的大小$O(NM)$，并且每次转换最多考虑$k_i$选项，给予$O(N \cdot M \cdot k_i)$，在最坏的情况下这太慢了。 

关键的观察是，尽管分配空间受到个体容量的限制，但该结构是有界整数组合问题。 我们将 M 个不可区分的项目分配到 N 个有上限的盒子中。 这可以建模为机器上的生成函数，其中每台机器贡献一个多项式$$P_i(x) = \sum_{j=0}^{k_i} x^j$$用于计算分布，以及用于成本的加权变体。 

我们不仅需要计数，还需要所有配置的成本总和。 这建议在分配的总任务中维护两个 DP 阵列：一个用于计算配置，另一个用于累计加权成本贡献。 

对于每台机器 i，当我们决定它接收 j 个任务时，它通过将索引移动 j 来贡献所有全局状态。 过渡是线性卷积，并且由于总 M 最多为$10^4$，一个背包式DP就足够了。 

微妙的改进是认识到我们从不需要每台机器的完整组合枚举，只需要有界 j 上的前缀转换，这会产生可管理的$O(NM)$解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举| 指数| O(N) | 太慢了|
 | 机器和负载上的DP | O(NM^2) | O(M)| 太慢了|
 | 优化的有界背包DP | O(NM) | O(M)| 已接受 |

 ## 算法演练

 我们对迄今为止处理的已分配提交总数保持一个 DP。 让`dp_cnt[s]`是将任务分配给已处理机器的方式数量，使得分配的任务总数为 s。 让`dp_sum[s]`是所有此类分配的累计运行时间总和。 

我们仅使用空赋值进行初始化。 

### 1.初始化

 套装`dp_cnt[0] = 1`和`dp_sum[0] = 0`。 所有其他状态均为零。 这相当于尚未分配任何内容。 

### 2. 一台一台加工机器

 对于每台机器 i，我们构建新的 DP 阵列`ndp_cnt`和`ndp_sum`从当前状态。 

### 3. 在机器 i 上尝试所有可行的负载

 对于从 0 到 k_i 的每个可能的 j，我们考虑将 j 个任务分配给这台机器。 该机器对负载 j 的贡献为`j * t[i][j]`。 

该值应用于之前有 s 个任务的每个全局状态，产生一个新状态 s + j。 

### 4. 转换计数

 对于每个 s 和 j：

 我们添加`dp_cnt[s]`进入`ndp_cnt[s + j]`因为每个现有配置都可以通过将 j 任务分配给机器 i 来扩展。 

这保留了对所有有效分布进行一次计数的结构。 

### 5. 过渡总和

 对于成本贡献，每个分机贡献之前的累计金额加上新机器的成本：`dp_sum[s] + dp_cnt[s] * (j * t[i][j])`。 

这是正确的，因为每个配置都计入`dp_cnt[s]`当选择 j 时，机器 i 会获得相同的额外成本。 

### 6.更换DP

 处理完所有j后，我们交换`dp`和`ndp`。 

### 为什么它有效

 在任何时候，`dp_cnt[s]`精确计算在已处理的机器之间分配任务的方式数量，从而达到总数 s，因为每台机器都独立地在有界选择上做出贡献，并且转换保留了精确的枚举而无需重复。 

为了`dp_sum[s]`，每个配置都会贡献其累积成本，并且当通过机器选择 j 进行扩展时，我们添加该机器的正确边际成本乘以达到先前状态的配置数量。 这确保了对所有有效分配的显式枚举的期望线性。 

由于 DP 精确地隐式枚举所有有效配置，并根据正确的总成本对每个配置进行加权，因此对所有最终状态求和即可得出所需的运行时间总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    N = int(input())
    
    machines = []
    total_cap = 0
    
    for _ in range(N):
        arr = list(map(int, input().split()))
        k = arr[0]
        t = arr[1:]
        machines.append((k, t))
        total_cap += k
    
    M = int(input())
    M = min(M, total_cap)
    
    dp_cnt = [0] * (M + 1)
    dp_sum = [0] * (M + 1)
    dp_cnt[0] = 1
    
    for k, t in machines:
        ndp_cnt = [0] * (M + 1)
        ndp_sum = [0] * (M + 1)
        
        for s in range(M + 1):
            if dp_cnt[s] == 0:
                continue
            base_cnt = dp_cnt[s]
            base_sum = dp_sum[s]
            
            for j in range(0, min(k, M - s) + 1):
                ways = base_cnt
                ndp_cnt[s + j] = (ndp_cnt[s + j] + ways) % MOD
                
                add_cost = (j * t[j - 1]) if j > 0 else 0
                ndp_sum[s + j] = (ndp_sum[s + j] + base_sum + ways * add_cost) % MOD
        
        dp_cnt, dp_sum = ndp_cnt, ndp_sum
    
    print(sum(dp_sum) % MOD)

if __name__ == "__main__":
    solve()
```该代码完全按照描述实现了两层 DP。 这`dp_cnt`array 跟踪有多少部分分配导致每个总负载。 这`dp_sum`数组累积所有这些分配的总运行时贡献。 

对于每台机器，我们尝试所有可行的分配 j。 转换会更新配置数量及其累积成本。 在每一步都应用模数以防止溢出。 

一个微妙的实现细节是，成本项仅取决于当前机器和选择的 j，而不取决于以前的机器，这就是为什么它可以直接添加为`ways * add_cost`。

 ## 边缘情况

 一个关键的边缘情况是，除了一台机器之外，所有机器的容量都为零。 在这种情况下，所有 M 任务必须发送到一台机器，并且 DP 应该崩溃到一个有效的配置。 该算法处理此问题是因为 k=0 的所有转换仅允许 j=0，从而保持 dp 状态不变。 

另一个边缘情况是当 M 超过总容量时。 代码将 M 限制为总容量，确保永远不会考虑无法到达的状态。 这可以避免 DP 溢出到不可能的配置并保持运行时间有限。 

第三种情况是 t[i][j] 随着 j 快速增长。 由于每个状态都是根据机器选择独立加权的，因此 t 的单调性与正确性无关，仅确保减速行为的真实建模。
