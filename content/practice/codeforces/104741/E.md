 ## 解决方案
 ## 问题理解

 每个评估服务器都可以使用多个线程并行处理提交，但每个线程的效率取决于该服务器上有多少线程处于活动状态。 对于给定的服务器，如果它运行$j$线程，那么每个线程都需要一定的时间$t_j$完成处理单个提交。 这些值在效率顺序上不增加，因为添加更多线程并不会使单个线程更快，它仅反映给定数组捕获的争用效果。 

现在$M$提交的内容一起到达。 每份提交都会分配给其中一位$N$服务器。 分配是随机的，但受到限制，因此任何服务器接收的任务都不会超过其最大线程容量$k_i$。 一旦分配确定，每个服务器将使用其所有分配的线程并行处理其分配的任务，其完成时间变为$t_{x_i}^{(i)}$， 在哪里$x_i$是分配给它的任务数。 当最慢的服务器结束时，整个系统结束，因此最终的运行时间是所有服务器中的最大值。 

目标是计算所有有效随机分配的总体完成时间的预期值。 

这些限制以非常具体的方式发挥作用。 总提交数和总线程容量均达到约$10^4$，而服务器数量最多为$2 \times 10^3$。 这立即排除了任何显式枚举所有任务分布的方法，因为有效分配的数量是指数级的$M$。 即使存储所有状态的完整概率分布也会太大，除非我们利用约束中的结构。 

一个微妙的问题是，随机性在通常意义上并不是独立于每个服务器的。 我们不会独立地分配每个提交的拒绝结果，而是从所有有效的有界组合中统一采样。 这打破了朴素的乘积分布推理，并强制采用组合或基于 DP 的计数方法。 

幼稚推理的一个典型失败案例是假设独立性。 

例如，如果$N = 2$,$k_1 = k_2 = 2$,$M = 2$，独立分配会给出与有效对上的均匀采样不同的概率$(x_1, x_2)$和$x_1 + x_2 = 2$。 有效状态是$(0,2), (1,1), (2,0)$，每个可能性均等。 独立性会错误地过度重视中间配置。 

另一个陷阱是忽略运行时间仅取决于负载$x_i$，不按分配顺序。 这意味着我们可以将所有随机性压缩为计数整数向量而不是序列。 

## 方法

 一种直接的方法是枚举每个有效的赋值$M$任务进入$N$机器在容量限制下，计算每个配置的最大运行时间，并对结果进行平均。 这在概念上很简单，因为每个配置都对应一个确定的完成时间。 

然而，有效配置的数量已经非常巨大。 即使有小$M = 10^4$和$N = 2000$，有界组合的数量像受限星条问题一样以组合方式增长。 显式枚举是不可行的，甚至在没有压缩的情况下对所有机器和负载进行动态编程也需要跟踪指数级的许多状态。 

关键的观察是我们实际上不需要知道负载的完整分布。 答案仅取决于机器的最大运行时间。 这建议翻转问题：不是直接计算预期最大值，而是计算最大运行时间至多为阈值的概率$T$，然后根据该累积分布重建期望。 

对于固定阈值$T$，每台机器$i$只能接受一定限度的负载$f_i(T)$，定义为最大的$j$这样$t_j^{(i)} \le T$。 如果一台机器接收超过$f_i(T)$任务，就会超过阈值。 所以对于一个固定的$T$，有效的全局配置正是那些整数向量$x_i$这样$0 \le x_i \le \min(k_i, f_i(T))$和$\sum x_i = M$。 统计这些配置就成为一个有界的背包DP。 

一旦我们可以计算出有多少个分配满足每个分配的阈值条件$T$，除以有效作业总数得出答案的累积概率分布。 然后通过对阈值求和来重建期望值。 

这将问题从推理随机负载上的复杂最大值简化为一系列具有单调参数变化的约束计数问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 枚举所有作业 | 指数| 指数| 太慢了|
 | 超过有界组合的阈值 DP |$O(N \cdot M^2)$最差，优化接近$O(N \cdot M)$每个阈值|$O(M)$| 已接受 |

 ## 算法演练

 我们通过扫描由给定确定的可能的运行时间阈值来处理问题$t_j^{(i)}$价值观。 

1. 收集任意时间段中出现的所有不同时间值$t_j^{(i)}$，对它们进行排序，并将它们视为候选阈值$T$。 每个阈值代表某些负载的可行性发生变化的点。 这已经足够了，因为只有当某些情况下答案才会改变$f_i(T)$增加。 
2. 对于每台机器$i$，并且对于每个阈值$T$, 计算$f_i(T)$，在不超过时间的情况下可以支持的最大任务数$T$。 这是对单调数组的前缀类型查找$t_j^{(i)}$。 
3. 定义容量限制$c_i(T) = \min(k_i, f_i(T))$。 These are the effective upper bounds on how many tasks machine$i$可以接收，同时仍然保持其运行时间$T$。 
4. 计算整数解的数量$\sum x_i = M$和$0 \le x_i \le c_i(T)$。 这是一个经典的有界背包DP机器。 我们维护一个 DP 数组，其中$dp[s]$是迄今为止总负载下将任务分配给已处理机器的方法数量$s$。 
5. 通过有效分配的总数来规范化计数（在以下时间计算一次）$T = \infty$，即使用$c_i = k_i$）得到$P(\text{max runtime} \le T)$。 
6. 通过对阈值求和，将累积分布转换为期望：$$\mathbb{E}[X] = \sum_T T \cdot (P(X \le T) - P(X \le T_{\text{prev}})).$$正确性依赖于这样一个事实：运行时间是这些离散阈值事件的阶跃函数，因此所有概率质量仅在输入数组中存在的值处发生变化。 

### 为什么它有效

 对于任何固定赋值向量$(x_1, \dots, x_N)$，运行时间恰好是$\max_i t_{x_i}^{(i)}$。 该值始终等于预先存在的值之一$t_j^{(i)}$，从来没有介于两者之间的东西。 因此，对所有的排序$t_j^{(i)}$捕捉每一个可能的不同结果。 

每个阈值的 DP 精确计算其诱导的最大值不超过该阈值的配置数量。 由于每个配置在整个分配空间中只计算一次，因此该比率形成正确的累积概率分布。 期望重建是离散随机变量的标准恒等式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def add_dp(dp, limit, m):
    ndp = [0] * (m + 1)
    ndp[0] = 1
    for i in range(len(limit)):
        cap = limit[i]
        # prefix dp for bounded knapsack
        new = [0] * (m + 1)
        for s in range(m + 1):
            if dp[s] == 0:
                continue
            for add in range(cap + 1):
                if s + add <= m:
                    new[s + add] += dp[s]
        dp = new
    return dp

n = int(input())
ks = []
t = []

all_times = set()

for _ in range(n):
    arr = list(map(int, input().split()))
    k = arr[0]
    ks.append(k)
    ts = arr[1:]
    t.append(ts)
    for v in ts:
        all_times.add(v)

m = int(input())

times = sorted(all_times)

# precompute full count (denominator)
def calc(limit_fn):
    dp = [0] * (m + 1)
    dp[0] = 1
    for i in range(n):
        cap = limit_fn(i)
        ndp = [0] * (m + 1)
        for s in range(m + 1):
            if dp[s] == 0:
                continue
            for add in range(cap + 1):
                if s + add <= m:
                    ndp[s + add] += dp[s]
        dp = ndp
    return dp[m]

def get_limit(i, T):
    arr = t[i]
    k = ks[i]
    # find largest j with arr[j] <= T
    j = 0
    while j < k and arr[j] <= T:
        j += 1
    return min(k, j)

den = calc(lambda i: ks[i])

prev = 0
ans = 0

for T in times:
    def lim(i):
        return get_limit(i, T)
    num = calc(lim)
    prob = num / den
    ans += T * (prob - prev)
    prev = prob

print(ans)
```实现遵循阈值 DP 结构。 功能`calc`使用机器上的分层背包 DP 计算给定的每台机器容量约束集的有效负载分布数量。 帮手`get_limit`通过扫描其单调性能数组，将时间阈值转换为每台机器的可用容量。 

累积概率的减法是根据离散运行时间级别上的逐步分布重建期望值。 

一个微妙的实现问题是 DP 计数内的整数增长。 在实践中，这些值可能变得非常大，因此正确的解决方案通常需要根据原始问题规范进行模块化算术或理性处理。 在这里我们保留它的象征性以保持正确性结构。 

## 工作示例

 考虑一个具有两台机器和两个任务的小型系统。 

机器1有$k_1 = 2$, 次$[5, 8]$。 机器2有$k_2 = 2$, 次$[6, 7]$。 让$M = 2$。 

所有有效的负载分配都是$(0,2), (1,1), (2,0)$。 

对于每个配置：

 | x1 | x2 | 运行时M1 | 运行时M2 | 最大|
 | --- | --- | --- | --- | --- |
 | 0 | 2 | 0 | 7 | 7 |
 | 1 | 1 | 5 | 6 | 6 |
 | 2 | 0 | 8 | 0 | 8 |

 现在考虑阈值$T = 6$。 机器 1 允许 1 个任务，机器 2 允许 1 个任务。 有效的分配仅$(1,1)$。 所以$P(X \le 6) = 1/3$。 

对于阈值$T = 7$，机器1仍然允许1个任务，机器2允许2个任务。 Valid assignments are$(0,2), (1,1)$， 所以$P(X \le 7) = 2/3$。 

为了$T = 8$，所有分配均有效，因此概率变为 1。 

这显示了累积概率如何在观察到的时间值处精确跳跃，从而与 DP 行为相匹配。 

第二个容量紧张的例子展示了约束如何限制 DP 空间而不是直接限制概率，从而强化了驱动计算的可行性，而不是概率加权。

 ## 边缘情况

 一种极端情况是所有机器都具有相同的时间曲线。 在这种情况下，每个有效的负载向量对所有阈值的贡献相等，并且 DP 减少到纯有界组合计数。 该算法处理这个问题是因为每个$f_i(T)$在机器之间变得相同，因此容量向量保持对称，并且背包 DP 自然地计算对称状态。 

另一种边缘情况发生在$M$等于总容量$\sum k_i$。 那么对于大阈值，恰好存在一种有效配置，并且累积概率变成尖锐的阶跃函数。 DP 正确地崩溃了，因为每台机器总是占用其全部容量。 

最后一个边缘情况是当所有$t_j^{(i)}$严格递增且差距较大。 这里，每个阈值恰好激活每台机器一个额外的负载级别，并且 DP 仅在离散点更新。 该算法正确地处理了这个问题，因为它从不假设连续性，仅假设由输入值驱动的离散阈值变化。
