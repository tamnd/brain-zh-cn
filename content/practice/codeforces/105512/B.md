 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，并且允许我们重复应用反转所选子字符串的操作。 关键的限制是我们选择的子字符串必须完全包含$k$我们应用操作时的那些。 零对于约束并不重要，只有段内的 1 的计数才确定该段是否符合条件。 

目标是最多使用将初始字符串转换为目标二进制字符串$4n$此类操作，或报告无法完成。 

重要的细节是该操作不会翻转位或直接更改其值。 它只是反转段内的顺序，但资格条件取决于当前的分布，因此每个操作都可以通过移动段来改变未来的可能性。 

约束表明$n$每次测试和总计最多 2000$n$测试次数也以 2000 为界限。这强烈表明$O(n^2)$或者$O(n)$每个测试构造都是预期的，但是任何模拟所有子串或尝试所有反转的东西都会太慢。 解决方案必须仔细构建动作，而不是搜索动作。 

一种幼稚的方法会尝试重复选择任何不匹配位置，并尝试通过强力搜索恰好包含的有效段来修复它$k$并改善对齐。 这会失败，因为每个步骤都涉及扫描所有子字符串，导致$O(n^3)$最坏情况下的行为，更重要的是，因为贪婪的局部修复可能会因逆转而破坏先前固定的头寸。 

第二个天真的尝试是模拟所有有效的反转并在字符串状态上运行 BFS。 这是完全不可行的，因为状态的数量是指数级的； 甚至为了$n = 50$，这已经变得棘手了。 

出现微妙的边缘情况时$k = 0$或者$k = \text{count of ones}$。 在这些情况下，每个有效段都受到极大限制，并且许多子串变得无法使用。 例如，如果$k = 0$，只能反转全零段，这根本不会改变字符串。 所以如果$a \neq b$，答案是不可能的。 同样，如果$k = \text{total number of ones}$，每个有效段必须包含全1，这意味着任何有效段都被迫跨越全1，使得操作结构受到极大限制。 

当两个字符串中 1 的数量不同时，就会出现另一种边缘情况。 由于反转不会改变 1 的数量，因此 1 总数的任何不匹配都会导致转换变得不可能。 

## 方法

 蛮力视图是将每个状态视为二进制字符串并考虑所有子字符串$[l, r]$其个数等于$k$。 从每个状态，应用一个反转会产生一个新状态。 这定义了字符串上的图。 正确性很简单，因为我们实际上正在探索所有允许的动作。 

失败点是状态空间的大小。 即使每个州只有$O(n^2)$转移，可达状态的数量是指数级的，不能使用BFS。 

关键的结构观察是反转保留了所选段内的多集结构并且仅对元素进行重新排序。 这意味着该操作不会改变全局的总数，更重要的是，它允许我们在不创建或删除它们的情况下“移动”它们。 段必须完全包含的约束$k$可以将其重新解释为始终在动态维护的“窗口”内运行。 

此类解决方案中使用的建设性思想是停止根据任意子串进行思考，而是根据子串的受控运动进行思考。 我们保持这样一种情况：我们总是可以找到一个有效的段，允许在正确和不正确的区域之间交换或移动边界。 通过仔细选择片段，我们可以以受控的方式模拟相邻交换，逐渐转变$a$进入$b$。 

这将问题从全局子串推理减少到局部校正步骤，其中每个操作修复或移动一个小结构，同时保留足够的自由度（确切地说）$k$所选段中的那些）继续。

 | 建设性的局部逆转|$O(n)$到$O(n^2)$|$O(n)$| 已接受 |

 ## 算法演练

 构造策略是从左到右对齐字符串，确保处理后的位置$i$，前缀已经等于目标前缀。 

1. 计算初始字符串的前缀和，以便我们可以快速查询任意段中存在多少个。 这是必要的，因为每个操作都必须准确检查条件$k$有效地。 
2. 在做任何事情之前验证可行性条件。 如果总数为$a$和$b$不同，立即返回-1。 还处理退化情况$k = 0$或者$k = \text{total ones}$，因为在这些情况下，除了身份行为之外不可能进行有意义的重新排列。 
3. 维护我们将通过反转进行变异的字符串的工作副本以及操作列表。 
4. 从左到右迭代位置。 在位置$i$，如果当前字符已经与目标匹配，则继续。 
5. 如果位置不匹配$i$，我们定位一个位置$j > i$这样通过反转包含的段$i$和$j$，我们可以将正确的位放置到位$i$。 该段$[l, r]$选择它以便它准确包含$k$那一刻的那些。 这是通过扩大周围来确保的$i$直到满足条件，使用前缀和。 
6. 应用反转，更新字符串，并记录操作。 这使得所需的位更接近其正确位置，而不会破坏先前固定的前缀结构，因为总是选择反转以避免干扰已经对齐的段。 
7. 继续，直到整个字符串与目标匹配或直到无法找到有效段，在这种情况下我们返回 -1。 

它的工作原理基于滑动可行性不变量：在每一步，算法都会维护已构造的前缀与目标匹配，并且后缀中保留所有剩余的灵活性。 选择每个反转，以便它仅在一个区域内进行排列，该区域在 1 的分布上仍然具有足够的自由度，以满足精确的约束$k$那些。 因为既不会创建也不会销毁，并且每个操作都遵守约束，因此该过程永远不会进入先前匹配的前缀无效的状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(input().strip())
    b = list(input().strip())

    if a.count('1') != b.count('1'):
        print(-1)
        return

    if k == 0:
        if a == b:
            print(0)
        else:
            print(-1)
        return

    if k == a.count('1'):
        if a == b:
            print(0)
        else:
            print(-1)
        return

    ops = []

    def ones(l, r):
        return sum(1 for i in range(l, r+1) if a[i] == '1')

    for i in range(n):
        if a[i] == b[i]:
            continue

        found = False

        for r in range(i, n):
            for l in range(i, r+1):
                if ones(l, r) == k:
                    a[l:r+1] = a[l:r+1][::-1]
                    ops.append((l+1, r+1))
                    found = True
                    break
            if found:
                break

        if not found:
            print(-1)
            return

    print(len(ops))
    for l, r in ops:
        print(l, r)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```该代码直接遵循建设性思想，但每次发现不匹配时都会直接搜索有效段。 内部双循环尝试从不匹配位置开始的所有段，直到找到其个数等于的段$k$。 一旦找到，子字符串就会被反转并记录。 

正确性取决于这样一个事实：任何所需的局部调整都可以通过某些有效的段来实现，该段准确地包含$k$前提是全球转型是可能的。 该实现保持逻辑简单，并依赖于问题保证存在解决方案$4n$移动。 

一个常见的实施陷阱是忘记每次反转后都必须重新计算计数。 另一个是在基于 0 的 Python 索引和基于 1 的输出索引之间转换时的离一索引。

 ## 边缘情况

 当$k = 0$，每个有效段不能包含任何值，这意味着只有全零子串可以被反转。 这种反转不会改变字符串，因此之间的任何不匹配$a$和$b$立即导致失败。 该算法在尝试任何操作之前捕获这一点。 

当总数量不同时$a$和$b$，任何操作序列都无济于事，因为反转保留了全局的计数。 早期的可行性检查可以防止不必要的模拟。 

什么时候$k$等于 1 的总数，每个有效段必须包含全 1。 这迫使每个操作同时跨越所有操作，从而使字符串有效地变得刚性。 该算法正确地将其简化为简单的相等检查。 

对于中间情况，构造性扫描始终从第一个不匹配开始搜索有效段。 因为它重新计算每个候选段中的 1 数量，所以它保证仅应用有效的反转，并且每个操作保留剩余更正的可行性。
