 ## 解决方案
 ## 问题理解

 我们需要用尽可能多的地雷方块建造一个矩形扫雷板。 一个地雷方块不能完全被其他地雷包围，因为每个地雷必须接触至少一个空的方块。 空的方块可能会接触到一些地雷，但相邻的地雷数量不能超过给定的限制`M`。 棋盘尺寸很小，有 2 到 6 行和列，我们必须只输出尽可能多的地雷。 原始问题约束和示例来自 ICPC Tishreen 大学编程竞赛问题档案。 

小尺寸是关键。 一块板最多有 36 个单元，因此不可能尝试每个完整的板，因为有`2^(r*c)`的可能性。 对于 6 x 6 板，这是`2^36`，这远远超出了我们所能列举的范围。 然而，一行最多包含 6 个单元格，因此只有`2^6 = 64`可能的行模式。 这建议逐行处理董事会并仅记住影响未来决策的行。 

困难的情况不是大量的投入，而是边界情况。 边缘上的行的邻居较少，因此将每个单元格视为有八个邻居可能会产生错误的答案。 

例如，输入：```
2 2 1
```整个棋盘有四个格子，一个空格子最多可以触及一个地雷。 对角线放置两个地雷是无效的，因为每个地雷只接触地雷，而不接触空单元格。 如果一个粗心的解决方案只检查空单元格，就会错误地允许两个地雷。 

另一种情况是：```
2 2 8
```答案是`3`， 不是`4`。 布满地雷的棋盘违反了每个地雷必须有一个空邻居的规则。 仅检查空单元格周围地雷最大数量的解决方案将接受无效的全地雷板。 

第三个常见错误出现在 DP 内的单行中。 对于顶行，单元格上方没有行。 如果实现意外地将缺失行视为包含地雷，则会拒绝边界附近的有效配置。 

## 方法

 蛮力方法很简单。 我们可以将我的或空的分配给每个单元格，然后验证这两个规则。 对于具有`r*c`细胞，这检查`2^(r*c)`板。 最大的电路板有 36 个单元，`68,719,476,736`的可能性。 即使非常快的验证步骤也无法使之变得可行。 

有用的观察是规则是本地的。 一个小区是否有效仅取决于它本身和八个相邻小区。 当我们选择一个新行时，唯一完全确定的行是新行上方两个位置的行。 一旦我们有了连续的三行，我们就可以验证中间的行，而无需再次查看它。 

这导致了基于行的动态编程。 一行存储为位掩码。 位值为 1 意味着该单元格是一个地雷。 DP 会记住最后两行，因为添加下一行可以让我们验证旧行。 

蛮力之所以有效，是因为它检查了每一个可能的棋盘。 它失败是因为它多次重复相同的本地情况。 DP 通过将具有相同最后两行的所有部分板分组为一种状态来消除这种重复。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^(r_c) * r_c) | O(2^(r_c) * r_c) | O(r*c) | 太慢了|
 | 最佳| O(r * 2^(3*c)) | O(r * 2^(3*c)) | O(2^(2*c)) | O(2^(2*c)) | 已接受 |

 ## 算法演练

 1. 用位掩码表示每一行。 对于一行`c`列，有`2^c`可能的面具。 少量`1`意味着我的和一点`0`意思是空的。 
2. 从上到下处理行。 DP 状态存储前两行以及迄今为止放置的最佳地雷数量。 添加新行时，我们有三个连续的行可用。 
3. 检查这三行的中间。 对于每个空单元格，计算三行中相邻位置之间的地雷数量。 如果计数大于`M`，过渡无效。 
4. 检查中间一排的每个地雷。 如果三行内没有相邻的空单元格，则转换无效。 
5. 如果中间行有效，则将窗口向前移动。 新状态保留最后两行，并在新行中添加地雷数量。 
6. 选择所有行后，使用最后一行下方的假想空行验证最后一行。 答案是所有已完成状态中的最佳值。 

这样做的原因是，当所有可能的邻居都已知时，每个单元都会被准确地检查。 选择下一行后，一行不能影响任何较早的行，因此从状态中丢弃它不会丢失任何必要的信息。 DP不变量是每个存储的状态代表所有可能的有效部分板，其具有相同的最后两行以及其中的最大地雷数。 

## Python 解决方案```python
import sys
from functools import lru_cache

input = sys.stdin.readline

def solve_case(r, c, limit):
    masks = list(range(1 << c))
    pop = [x.bit_count() for x in masks]

    def valid(upper, middle, lower):
        for col in range(c):
            cnt = 0
            if ((middle >> col) & 1) == 0:
                for row_mask in (upper, middle, lower):
                    for dc in (-1, 0, 1):
                        nc = col + dc
                        if 0 <= nc < c and ((row_mask >> nc) & 1):
                            cnt += 1
                if cnt > limit:
                    return False

            else:
                has_empty = False
                for row_mask in (upper, middle, lower):
                    for dc in (-1, 0, 1):
                        nc = col + dc
                        if 0 <= nc < c and ((row_mask >> nc) & 1) == 0:
                            has_empty = True
                if not has_empty:
                    return False
        return True

    @lru_cache(None)
    def dp(row, prev2, prev1):
        if row == r:
            return pop[prev1] if valid(prev2, prev1, 0) else -10**9

        ans = -10**9
        for cur in masks:
            if row == 0:
                ans = max(ans, dp(row + 1, 0, cur) + pop[cur])
            else:
                if valid(prev2, prev1, cur):
                    ans = max(ans, dp(row + 1, prev1, cur) + pop[cur])
        return ans

    return dp(0, 0, 0)

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        r, c, m = map(int, input().split())
        ans.append(str(solve_case(r, c, m)))
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```行掩码为每个测试用例生成一次。 这`valid`功能是解决方案的核心。 它接收三个相邻行并决定中间行是否满足扫雷规则。 

递归DP使用`(row, prev2, prev1)`作为它的状态。`prev2`和`prev1`是紧邻要放置的下一行上方的两行。 当选择下一行时，旧的中间行变得完全可检查。 

通过在最后一行之后传递零掩码来处理底部边框。 这代表没有地雷的行，并且避免了验证逻辑内部的特殊处理。 

Python 整数具有任意精度，因此不存在溢出问题。 唯一的索引危险是检查相邻列，这就是为什么每个列访问都会验证`0 <= nc < c`。

 ## 边缘情况

 对于`2 2 1`在这种情况下，DP 从棋盘周围的空虚拟行开始。 完整的矿井板会失败，因为每个矿井没有相邻的空单元。 转换验证器在提供答案之前会拒绝它。 

对于`2 2 8`在这种情况下，空单元限制消失，因为每个空单元都可能接触所有八个邻居。 该算法仍然检查单独的地雷要求，因此它会找到具有三个地雷的最佳板，而不是错误地返回四个。 

对于边界行，虚拟零掩码表示缺失的外部行。 这意味着角地雷只需要棋盘上实际存在的空邻居，符合真正的扫雷邻居规则。
