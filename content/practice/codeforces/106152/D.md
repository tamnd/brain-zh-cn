 ## 解决方案
 ## 问题理解

 我们需要建立一个`r × c`扫雷板。 

每个单元格要么是一个地雷，要么是一个空单元格。 

一个有效的董事会必须满足两个条件。 

对于每个地雷，至少有一个相邻单元格必须是空的。 

对于每个空单元格，相邻地雷的数量不得超过`M`。 

邻居是常见的扫雷邻居，最多 8 个单元格并排或角落接触。 

在所有有效的棋盘中，我们希望地雷的数量尽可能多。 

尺寸非常小，`2 ≤ r, c ≤ 6`， 尽管`1 ≤ M ≤ 8`。 棋盘最多包含 36 个单元，因此暴力破解所有地雷布置需要检查最多`2^36`配置，这是完全不可能的。 

小宽度和高度表明采用状态压缩方法。 由于每个扫雷约束仅取决于距离 1 内的单元格，因此单元格的有效性仅取决于其自身的列和两个相邻列。 该地点是关键观察点。 

边界处出现微妙的边缘情况。 

考虑第一列中的一个地雷。 棋盘外的单元格不是空单元格。 将“棋盘外”视为空单元的粗心实现将错误地允许这样的地雷满足具有空邻居的要求。 

例如：```
**
**
```每个细胞都是一个矿井。 任何矿井都没有空邻居，因此该板无效。 

另一个边缘情况是空角单元。 它只有三个邻居，而不是八个。 

例如：```
..
.*
```左上角只有一个相邻的矿井。 将不存在的细胞计数为邻居会产生错误的结果。 

最后一个重要的边缘情况是，只有在已知两个相邻列之后才能完全验证单元格。 过早检查某一列可能会错过下一列的信息。 

## 方法

 暴力解决方案很简单。 枚举每个子集`r × c`单元格作为地雷集合，然后检查两个有效性条件。 由于电路板可以包含 36 个单元，因此需要检查`2^36 ≈ 6.8 × 10^10`配置，这远远超出了任何现实限制。 

蛮力正确的原因是它直接测试每个可能的板。 它失败的原因是巨大的搜索空间。 

关键的观察是每个约束都是局部的。 

判断某个单元格是否在列中`j`有效，我们只需要列中的信息`j-1`,`j`， 和`j+1`。 更远的地方不会影响该细胞。 

自从`r ≤ 6`，一整列可以表示为最多 6 位的位掩码。 只有`2^r ≤ 64`可能的列状态。 

这将问题转化为轮廓动态规划问题。 

对于每个三重列掩码`(A, B, C)`，我们可以检查中间列的所有单元格是否`B`被柱包围时满足规则`A`和`C`。 

然后我们从左到右处理列。 DP 状态存储最后两个列掩码。 当添加新列时，我们可以立即验证中间列。 

搜索空间变得很小：`64 × 64 × 64 = 262144`最坏的情况下可能是三倍。 

这很容易管理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^(r·c) · r · c) | O(2^(r·c) · r · c) | O(1) | O(1) | 太慢了 |
 | 最佳轮廓 DP | O(c·2^(3r)) | O(c·2^(3r)) | O(2^(2r)) | O(2^(2r)) | 已接受 |

 ## 算法演练

 1. 将每一列表示为长度的位掩码`r`。 
2. 对于每个可能的三重掩码`(left, mid, right)`，判断中间列的每个单元格是否满足问题约束。 
3. 对于空单元格，计算现有相邻单元格中的相邻地雷。 计数不得超过`M`。 
4. 对于一个矿井小区，检查是否至少有一个相邻小区是空的。 
5. 存储所有有效的转换。 如果中间列的每个单元格都通过了测试，则三元组有效。 
6.添加两个mask哨兵列`0`，一个在第一个实列之前，一个在最后一个实列之后。 这些哨兵代表“没有单元格”，而不是实际的空单元格。 
7. 对列使用动态规划。 令状态为已选择的最后两个列掩码。 
8. 当尝试附加新的列掩码时，请使用相应的预先计算的三元组验证前一列是否有效。 
9. DP值是目前为止放置的最大地雷数量。 
10. 处理完所有真实列后，附加正确的标记并对最后一个真实列执行最终有效性检查。 
11、最大的DP值就是答案。 

### 为什么它有效

 细胞只与自己的列和两个相邻列中的细胞相互作用。 当算法验证一列时，可以影响该列的所有信息都是已知的。 

DP 从不接受无效的中间列，并且每个有效板恰好对应于 DP 处理的列掩码的一个序列。 

由于当所有相关的相邻信息可用时，每列都会被精确检查，因此无效的配置不会存在，也不会丢弃有效的配置。 DP 探索所有有效的棋盘并最大化其中的地雷数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        r, c, M = map(int, input().split())

        S = 1 << r

        def bit(mask, row):
            return (mask >> row) & 1

        valid = [[[False] * S for _ in range(S)] for _ in range(S)]

        for left in range(S):
            for mid in range(S):
                for right in range(S):
                    ok = True

                    for row in range(r):
                        cur = bit(mid, row)

                        mines = 0
                        has_empty = False

                        for dc in (-1, 0, 1):
                            for dr in (-1, 0, 1):
                                if dc == 0 and dr == 0:
                                    continue

                                nr = row + dr
                                if not (0 <= nr < r):
                                    continue

                                if dc == -1:
                                    mine = bit(left, nr)
                                elif dc == 0:
                                    mine = bit(mid, nr)
                                else:
                                    mine = bit(right, nr)

                                if mine:
                                    mines += 1
                                else:
                                    has_empty = True

                        if cur == 0:
                            if mines > M:
                                ok = False
                                break
                        else:
                            if not has_empty:
                                ok = False
                                break

                    valid[left][mid][right] = ok

        NEG = -10**9

        dp = [[NEG] * S for _ in range(S)]
        dp[0][0] = 0

        for _col in range(c):
            ndp = [[NEG] * S for _ in range(S)]

            for a in range(S):
                for b in range(S):
                    cur_val = dp[a][b]
                    if cur_val == NEG:
                        continue

                    for nxt in range(S):
                        if valid[a][b][nxt]:
                            ndp[b][nxt] = max(
                                ndp[b][nxt],
                                cur_val + nxt.bit_count()
                            )

            dp = ndp

        ans = 0

        for a in range(S):
            for b in range(S):
                cur_val = dp[a][b]
                if cur_val == NEG:
                    continue

                if valid[a][b][0]:
                    ans = max(ans, cur_val)

        print(ans)

solve()
```实现的核心是预计算`valid[left][mid][right]`。 

对于中间列中的每个单元格，我们检查 8 个可能的相邻位置。 板外的行将被跳过。 左右掩码自然提供有关相邻列的信息。 

DP从掩码的两个哨兵列开始`0`。 这些面具不计入董事会的一部分。 它们只允许使用与所有其他列相同的转换逻辑来检查第一个和最后一个实际列。 

错误的常见来源是忘记只有在已知相邻列的情况下才能验证该列。 因此，该状态保留两个连续的列掩码，而不是一个。 

另一个微妙的细节是我的计数。 当添加新列时，只有新列的地雷才会添加到分数中。 早期的列在引入时就已被计算在内。

 ## 边缘情况

 考虑董事会```
**
**
```每个细胞都是一个矿井。 没有一个我的邻居是空的。 在验证过程中，每个矿井都会检查所有现有的相邻小区，但从未发现空的小区，因此配置会被拒绝。 

考虑```
..
.*
```左上角只有三个有效的相邻位置。 该算法在计算邻近地雷时会跳过越界位置，因此计算结果正确。 

考虑一列在其右邻居已知之前显示为有效的列。 DP 不会在创建列后立即对其进行验证。 仅当两个相邻列都可用时才会进行验证。 这可以防止接受稍后因下一列而变得无效的配置。
