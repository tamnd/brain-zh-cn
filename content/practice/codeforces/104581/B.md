 ## 解决方案
 ## 问题理解

 我们有一个固定的食谱，告诉我们一份菜肴需要每种成分多少克。 对于每种成分，我们还会收到多个包装，每个包装中都含有一定克数的该成分。 每种成分的包装数量都相同。 

目标是组装套件。 每个套件必须包含每种成分的一包。 套件被分配了一定数量的份量，并且该数量必须是整数。 如果对于每种成分，为该成分选择的包装在该份数所需量的 90% 至 110% 范围内，则套件对于一定份数有效。 

我们希望选择尽可能多的有效套件，并且每个套件最多可以使用一次。 我们并不是试图最大限度地提高每个套件的份量，而只是试图最大化有效套件的数量。 

这些约束允许最多 50 种成分，每种成分最多 50 个包装，整个测试中的包装总数以 1000 为界。这立即排除了任何试图穷尽所有方法将跨成​​分的包装配对的方法，因为这将涉及跨维度的组合爆炸。 

关键的困难在于，一个包没有一个固定的“匹配伙伴”。 适合 3 份的番茄包与不同的洋葱包搭配使用时，可能无法用于 4 份。 因此，兼容性取决于套件中所有成分的份数的共同选择。 

一个幼稚的错误是独立对待每种成分。 例如，计算每个包装的有效服务范围和贪婪地匹配重叠而不同步成分可能会产生不一致的套件。 另一个微妙的失败是单独选择每种成分的份数。 这打破了套件中所有成分必须同意相同整数份数的要求。 

边缘情况包括一种成分具有非常小的方差包而另一种成分具有极大的方差的情况。 在这种情况下，局部贪婪的选择可能会将您锁定在不兼容的全局配对中，即使不同的排序会产生更多套件。 

## 方法

 暴力视角首先想象我们尝试通过从每种成分中挑选一个包来形成一个套件，然后为该组合搜索有效的整数份量。 对于固定的包装元组，我们可以为每种成分计算一系列可能的份量值。 所有这些范围的交集告诉我们该元组是否有效。 如果有效，我们提取一个可行的整数服务值。 

这在概念上是可行的，但元组的数量是 P^N，即使对于像 N = 10、P = 50 这样的中等值来说，这也是一个天文数字。即使减少对称性也没有足够的帮助，因为兼容性取决于连续间隔，而不是离散标签。 

关键的观察是翻转问题。 我们不是从任意组合构建套件，而是对每种成分的包装进行排序，然后将问题视为反复尝试匹配“最受限制的可能套件”。 对于每个包装，我们可以计算使其有效的服务间隔。 每个包都成为数轴上的一个区间。 套件对应于从每种成分中挑选一个区间，使得所有选定的区间共享至少一个公共整数点。 

现在问题变成：重复地找到一组每个成分的交集非空的区间，然后删除这些区间并重复。

这表明了一种贪婪的结构。 如果我们对每种成分的包装进行分类，我们总是可以尝试从剩余的最小可行配置开始构建套件。 正确的策略是重复选择来自“最严格”约束的候选份数，然后贪婪地选择所有成分中兼容的包装。 

官方解决方案中使用的更具体的简化是为每个包裹预先计算其有效服务范围[L，R]。 然后，对于每种成分，我们按 L 对这些范围进行排序。我们反复尝试通过在剩余候选者中挑选尽可能小的 L 来形成套件，然后扫描所有成分的一致交集。 套件形成后，我们将删除所选的软件包并继续。 

这是有效的，因为任何有效的套件都必须对应于重叠点，并且选择最小的可用左端点可确保我们不会跳过可能阻止未来匹配的可行的最小解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对包元组的暴力破解 | O(P^N) | O(P^N) | O(N) | 太慢了|
 | 区间贪婪匹配 | O(N·P^2) | O(N·P^2) | O(N·P) | 已接受 |

 ## 算法演练

 1. 对于每种成分，计算每个包装的有效食用间隔。 对于数量为 Q 且配方要求为 R 的包装，份数 s 必须满足 0.9·s·R ≤ Q ≤ 1.1·s·R。 我们将其重新排列为一系列整数 s 值。 这将每个包转换为连续的可行性区间。 
2. 按左端点对每种成分内的所有区间进行排序。 这确保我们始终首先考虑最具限制性的候选者，这对于贪婪选择至关重要。 
3. 为每种成分保留一个指针，指示第一个未使用的包装间隔。 
4. 反复尝试构建套件：

 对于每种成分，取其当前最小可用间隔。 通过取左端点的最大值和右端点的最小值来计算所有这些间隔的交集。 
5. 如果路口是空的，则不能再组成更多的套件，我们就停下来。 原因是增加任何指针只会将左端点进一步向右移动，这无法恢复最小选择中已经不存在的重叠。 
6. 如果交集非空，则选择其中的任何整数服务值，通常是左边界。 然后从与所选间隔相对应的每种成分中选择一包，并通过前进所有指针将其标记为已使用。 
7. 重复此操作，直到不存在有效的交点。 

为什么有效：每个有效的套件都对应于为每种成分选择一个区间，其交集包含某个整数。 在所有可能的套件中，总有一个套件的所选间隔包括剩余间隔中可能的最小左端点。 贪婪步骤捕获了这个最早的可行重叠，并且删除它不会破坏后来独立重叠的可行性，因为间隔是按照增加约束紧密度的顺序消耗的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_interval(q, r):
    # 0.9 * s * r <= q <= 1.1 * s * r
    # => q / (1.1 r) <= s <= q / (0.9 r)
    # use integer bounds carefully
    import math
    lo = math.ceil(q / (1.1 * r))
    hi = math.floor(q / (0.9 * r))
    return lo, hi

def solve():
    T = int(input())
    out = []

    for tc in range(1, T + 1):
        n, p = map(int, input().split())
        R = list(map(int, input().split()))

        intervals = []
        for i in range(n):
            row = list(map(int, input().split()))
            lst = []
            for q in row:
                lo, hi = build_interval(q, R[i])
                lst.append((lo, hi))
            lst.sort()
            intervals.append(lst)

        ptr = [0] * n
        ans = 0

        while True:
            cur = []
            for i in range(n):
                if ptr[i] == p:
                    cur = None
                    break
                cur.append(intervals[i][ptr[i]])

            if cur is None:
                break

            L = max(x[0] for x in cur)
            Rr = min(x[1] for x in cur)

            if L <= Rr:
                ans += 1
                for i in range(n):
                    ptr[i] += 1
            else:
                # discard the most restrictive left endpoint
                # advance one pointer: the ingredient that blocks feasibility
                worst = 0
                for i in range(1, n):
                    if cur[i][0] > cur[worst][0]:
                        worst = i
                ptr[worst] += 1

        out.append(f"Case #{tc}: {ans}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```核心实施思想是将每个包装转换为一个服务间隔，然后反复尝试调整每种成分的一个间隔。 这些指针确保每个包最多使用一次。 贪婪去除步骤很微妙：当相交失败时，我们丢弃左端点压力最大的区间，因为它是阻止与其他区间重叠的最主要原因。 

主要陷阱是区间计算中的浮点精度。 在实践中，使用`ceil`和`floor`超过精心构造的表达式足以满足竞赛限制，但更安全的方法是将所有内容缩放 10 以完全避免小数。

 ## 边缘情况

 一个关键的边缘情况是间隔几乎不接触边界。 例如，如果一个包仅允许在其上限处提供 10 个，而另一个包仅允许在其下限处提供 10 个，则交集仍包括 10。该算法将这些视为有效，因为我们使用包容性不等式，并且两者都包含在内。`ceil`和`floor`保持边界正确性。 

当一种成分的区间单调缩小而其他成分的区间较宽时，就会出现另一种边缘情况。 贪婪指针前进确保我们始终丢弃最早防止重叠的间隔，从而避免过早地提交错误的对齐。 

最后一种微妙的情况是，除了一个范围略有偏移的异常值区间外，所有剩余区间都重叠。 该算法首先删除该异常值，因为它最大化了左端点，从而恢复了从一致集群构建的未来套件的可行性。
