 ## 解决方案
 ## 问题理解

 我们得到一个由小写字母组成的字符串。 从这个字符串中，我们可以删除字符，同时保持剩余字符的顺序，并且我们只对结果的回文子序列感兴趣。 

这项任务是双重的。 首先，我们必须判断是否存在长度正好为100的回文子序列。如果存在这样的子序列，我们可以输出其中的任何一个。 如果不存在，则要求我们输出可以从给定字符串构造的最长回文子序列。 

关键的困难在于我们不是针对子字符串而是针对子序列进行优化，这意味着只要保留顺序，我们就可以从任何地方选取字符。 这使得候选空间极大，直接枚举是不可能的。 

长度约束是解决方案的关键驱动因素。 字符串长度可以达到 50000，但我们只关心是否可以组装长度为 100 的回文。任何尝试计算整个字符串上最长回文子序列的完整 DP 表的解决方案都会太慢，因为经典的 LPS DP 是 O(n^2)，在最坏的情况下大约需要 25 亿次操作。 

当字符串具有许多重复字符但它们分布稀疏时，就会出现微妙的边缘情况。 例如，像交替字母这样的字符串可能仍然允许许多短回文，但不允许长度为 100。相反，一个字符几乎占主导地位的字符串几乎包含长回文。 一种天真的贪婪方法，在没有计划的情况下从末尾挑选匹配的字符，可能会很早就陷入困境，错过构建全长 100 回文的可能性，即使它存在。 

当最佳回文不以最常见的字符为中心时，就会出现另一种失败情况。 基于频率的贪婪解决方案可能会假设答案是根据最常见的字母构建的，但是当结构交错并且匹配对仅存在于不同的段之间时，这可能会失败。 

## 方法

 暴力方法会尝试在整个字符串上使用动态编程来计算最长的回文子序列。 这是通过考虑每个间隔并计算其中的最佳回文来实现的。 正确性是标准的，但状态空间为 O(n^2)，每次转换为 O(1)，导致 n = 50000 时约 25 亿次操作，这对于 2 秒的限制来说太慢了。 

关键的观察是，如果超过 100，我们不需要精确的最长回文子序列。我们只关心是否可以构建长度为 100 的回文子序列，否则我们只需要一些最大构造。 这将问题从全局优化转移到受控构建。 

回文的一个关键结构特性是它们是由围绕中心镜像的成对匹配字符定义的。 这意味着我们可以根据字符的配对出现来思考。 对于每个字母，我们可以将左端和右端的出现配对。 每对为回文贡献两个字符。 如果我们在字母之间积累对，我们就有效地构建了回文的外层。 

如果我们总共可以收集至少 50 对，我们就可以形成长度为 100 的回文。否则，我们采用所有可用的对以及可能的一个剩余的中间字符，这给出了最大可能的回文。 

因此，该结构简化为跟踪每个角色的位置并从相对的两端贪婪地形成对。 这是有效的，因为任何有效的回文子序列都必须对应于某些出现的配对，并且只要保留顺序，我们就可以自由选择任何有效的配对。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力DP | O(n^2) | O(n^2) | O(n^2) | O(n^2) | 太慢了 |
 | 配对贪婪构造 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们为每个字符维护它出现的索引列表。 从每个列表中，我们从外到内取对。 

1. 扫描字符串并分别存储每个字符的索引。 这保留了顺序，这是有效子序列所必需的。 
2. 对于每个字符，重复取出最左边和最右边未出现的字符并形成一对。 每个这样的对都为回文贡献两个字符。 
3. 将所有角色中的所有此类对收集到可用镜像对的全局列表中。 
4. 如果总对数至少为 50 对，则我们正好取 50 对。 这些决定了回文的左半部分。 然后我们镜像它们以形成右半部分。 
5. 如果少于 50 对，我们将采用所有可用的对。 左半部分是通过按顺序取出每对中的第一个元素而形成的，右半部分是通过反转第二个元素而形成的。 
6. 如果成对后还有剩余未使用的字符，我们将正好放置一个作为回文的中心。 
7. 输出结果序列。 

配对起作用的原因是每个回文子序列都可以分解为不相交的对称对加上可选的一个中心元素。 由于我们可以自由选择任何子序列，贪婪配对极端永远不会阻止未来的有效配对，因为删除配对元素不会降低其他配对的可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    pos = [[] for _ in range(26)]
    
    for i, c in enumerate(s):
        pos[ord(c) - 97].append(i)
    
    pairs = []
    
    for i in range(26):
        arr = pos[i]
        l, r = 0, len(arr) - 1
        while l < r:
            pairs.append((arr[l], arr[r], i))
            l += 1
            r -= 1
    
    # sort pairs by left index to preserve order
    pairs.sort(key=lambda x: x[0])
    
    k = min(50, len(pairs))
    
    left = []
    right = []
    
    used = set()
    
    for i in range(k):
        l, r, c = pairs[i]
        left.append(chr(c + 97))
        right.append(chr(c + 97))
        used.add(l)
        used.add(r)
    
    # if we need center
    center = ""
    if len(pairs) < 50:
        # pick any unused character
        used_set = set()
        for i in range(len(s)):
            used_set.add(i)
        for u in used:
            used_set.discard(u)
        if used_set:
            center = s[next(iter(used_set))]
    
    print("".join(left + [center] + right[::-1]))

if __name__ == "__main__":
    solve()
```该实现首先对每个字符的索引进行分组，确保我们知道所有可用的出现情况。 然后它从外到内构造候选镜像对。按左索引排序可确保当我们选择对时子序列顺序保持有效。 

的建设`left`和`right`数组对回文的两半进行编码。 右侧只是所选字符的相反，因为回文镜像结构。 

仅当我们未达到 50 对时，中心选择才重要。 在这种情况下，我们可能仍然有未使用的字符，并且其中任何一个都可以作为奇数长度回文的中间。 

一个微妙的点是，我们永远不需要在配对后显式检查排序的可行性，因为配对总是由增加的左索引和减少的右索引形成，从而保留了子序列的有效性。

### 示例 2

 输入：```
abacabadabacaba
```a 的位置密集，其他位置稀疏。 我们得到了很多对“a”和一些“b”和“c”。 

该算法将优先考虑每个字符块中的配对极值。 

| 步骤| 行动| 左| 对|

这表明该算法纯粹基于结构可用性而不是仅基于字符频率进行调整。

 ## 边缘情况

 当除了出现两次的字符之外的每个字符都只出现一次时，就会出现一种棘手的情况。 例如，`abcdeffedxyz`样式输入。 该算法只会从重复的字符中形成一对，并根据可行性正确地将其他所有内容放置为中心或丢弃。 配对逻辑确保我们永远不会尝试过度使用字符。 

另一种情况是当有很多对但不足以达到 50 个时。在这种情况下，算法简单地使用所有可用的对并构造最大可能的回文。 由于每一对恰好贡献两个字符，并且最多有一个中心，因此该结构仍然有效，不需要额外的检查。 

最后一种边缘情况是字符串已经包含长度为 100 或更长的完美回文。 在这种情况下，将至少有 50 个不相交对，算法自然会选择其中 50 个，从而生成有效的长度为 100 的回文子序列，而无需显式搜索连续结构。
