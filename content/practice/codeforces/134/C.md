 ## 解决方案
 ## 问题理解

 每个玩家最初都拥有一种颜色的牌，即他们自己的颜色。 玩家`i`开始于`a[i]`卡片，所有颜色`i`。 在交换过程中，两名玩家各交换一张牌。 玩家只能赠送自己颜色的牌，并且可能永远不会收到他们已经拥有的颜色。 

这个目标比简单地重新分配牌更强大。 每个玩家最终都必须摆脱自己颜色的所有牌。 由于玩家只能给出自己的颜色，因此每张颜色的牌`i`必须通过交换转移出去，直到没有人留在玩家手中`i`。 

对重复颜色的限制是核心难点。 一旦玩家收到颜色`x`，他们永远无法收到另一种颜色`x`再次。 即使存在解决方案，粗心的交换序列也很容易使进程陷入僵局。 

制约因素很大。 两个都`n`和`s`达到`2 * 10^5`，并且交换的总数也会变得很大。 任何重复扫描所有玩家或明确模拟卡牌所有权的算法都会太慢。 二次行为立即被排除。 该解决方案必须在产生的交换数量上接近线性时间。 

还有一个隐藏的计数条件。 每次交换都会从两名玩家中各删除一张牌。 如果玩家`i`开始于`a[i]`卡牌，然后是玩家`i`必须准确参与`a[i]`交换，因为每次交换都会让他们赠送一张卡。 总结所有玩家：$$\sum a[i]$$必须是偶数，因为每次交换都会贡献`2`到总参与数。 

仅此条件还不够。 一名玩家的参与次数也不能超过所有其他玩家的总和。 如果某个玩家的牌比其他玩家的牌多，最终其他人都会用完交换，而该玩家仍然有剩余的牌。 

例如：```
3 5
5 0 0
```玩家1需要五次交换，但玩家2和3一起只能参与零次交换。 正确答案是`No`。 

另一个微妙的情况是：```
3 3
1 1 1
```总和是奇数。 由于每次交换都会消耗两张卡，因此没有顺序可以完成所有三张卡。 正确答案是`No`。 

一个更有趣的有效案例是：```
4 4
2 1 1 0
```天真的贪婪策略可能会重复配对最大的计数，而不仔细跟踪接收到的颜色。 这可能会在以后产生重复颜色冲突。 正确的结构必须保证没有一对玩家交换超过一次，因为重复一对将迫使每个玩家两次获得相同的颜色。 

这一观察结果成为关键的结构见解。 

## 方法

 思考这个问题的强力方法是直接模拟卡的所有权。 在每一步中，我们都会寻找两个可以合法交换的玩家，执行交换，更新所有权集，并继续直到所有牌消失或没有合法的移动。 

如果最终成功的话，这种做法就是正确的，因为它确实遵守了游戏规则。 问题在于效率和状态复杂性。 每个玩家可能积累许多颜色，因此检查合法性需要维护大量颜色。 更糟糕的是，决定交换哪对并非易事。 即使存在有效的全局解决方案，错误的局部选择也可能导致以后陷入僵局。 

在最坏的情况下，最多可能有$$\frac{\sum a[i]}{2}$$交换，并且在每一步中对有效对的天真搜索变得二次或更糟。 

关键的观察是玩家永远不可能两次收到相同的颜色。 由于玩家`i`总是赋予颜色`i`, 其他玩家可以与玩家交换`i`最多一次。 

这彻底改变了问题。 

不要考虑卡片，而要考虑图表。 每次球员之间的交换`u`和`v`创建一个边缘。 因为两个玩家不能交换两次，所以图表必须很简单。 玩家等级`i`正好等于`a[i]`，因为他们必须参加多次交换才能赠送所有卡。 

现在任务变成：

 构造一个简单的无向图`n`度数序列为的顶点`a`。 

这是一个经典的图形序列问题。 

图形序列的标准贪婪构造是哈维尔-哈基米过程。 重复取出剩余度数最大的顶点并将其连接到其他几个度数最高的顶点。 每个连接都会将两个度数都减一。 

这完全符合交换解释。 正在连接`u`和`v`意味着我们在它们之间安排了一次交换。 

暴力模拟会失败，因为它会导致暂时的卡所有权状态。 图形解释完全消除了这种复杂性。 一旦我们确保没有边缘重复，颜色约束就会自动满足。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(s²) 或更差 | O(s) | 太慢了|
 | 最佳 | O(s log n) | O(s) | 已接受 |

 ## 算法演练

 1. 读取学位序列`a[i]`。 
2. 检查度数总和是否为偶数。 

每次交换都会贡献度`2`，每个端点一个。 奇数和使得不可能立即得到解决方案。 
3. 将所有具有正度数的玩家插入到按剩余度数排序的最大堆中。 
4.反复提取播放器`u`具有最大剩余度数`d`。 

玩家`u`还需要`d`不同的互换合作伙伴。 
5. 如果少于`d`其他玩家留在堆中，构建是不可能的。 

一张简单图无法将一个顶点连接到比当前存在的更多不同顶点。 
6.暂时删除下一个`d`堆中等级最高的玩家。 
7. 对于每个提取的玩家`v`:

 1.添加交换`(u, v)`到答案。 
2. 减少`v`的剩余度数减一。 
3. 商店`v`如果其程度保持正值，则重新插入。 
8.全部处理完毕后`d`邻居，将每个更新的玩家重新插入堆中。 
9. 继续，直到堆变空。 
10. 将所有构造的边作为交换输出。 

### 为什么它有效

 不变的是，剩余的度数总是描述部分构造的简单图的未完成的交换要求。 

当我们删除度数最大的顶点时`u`并将其连接到`d`不同的顶点，我们满足所需的所有剩余交换`u`一步之遥。 因为每个选择的邻居都是不同的，所以不会出现重复的边缘。 由于每条边对应一次交换，因此没有玩家会两次收到相同的颜色。 

哈维尔-哈基米定理保证，如果存在图形实现，则这种贪婪归约保留了可行性。 如果在某个步骤没有足够的不同顶点可供连接，则不存在具有所需度数的简单图。 

因此，当交换计划存在时，该算法会准确地构造一个有效的交换计划。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, s = map(int, input().split())
    a = list(map(int, input().split()))

    if sum(a) % 2:
        print("No")
        return

    pq = []

    for i, deg in enumerate(a, 1):
        if deg > 0:
            heapq.heappush(pq, (-deg, i))

    ans = []

    while pq:
        deg_u, u = heapq.heappop(pq)
        deg_u = -deg_u

        if deg_u > len(pq):
            print("No")
            return

        taken = []

        for _ in range(deg_u):
            deg_v, v = heapq.heappop(pq)
            deg_v = -deg_v

            ans.append((u, v))

            deg_v -= 1

            if deg_v < 0:
                print("No")
                return

            if deg_v > 0:
                taken.append((-deg_v, v))

        for item in taken:
            heapq.heappush(pq, item)

    print("Yes")
    print(len(ans))

    for u, v in ans:
        print(u, v)

solve()
```堆存储对`(-degree, vertex)`因此 Python 的最小堆的行为就像最大堆一样。 

最微妙的部分是可行性检查：```
if deg_u > len(pq):
```玩家`u`需要`deg_u`不同的邻居。 如果剩余的顶点少于那么多，则简单的图构造是不可能的。 

另一个微妙的细节是，我们在减少邻居后不会立即重新插入它们。 我们首先删除所有`deg_u`邻居，每个处理一次，然后将更新的值推回。 这保证了所有邻居都是不同的，防止重复的边缘。 

该算法从不明确跟踪卡片颜色。 图形结构已经强制执行颜色规则。 由于每对玩家最多交换一次，因此任何玩家都不能两次获得相同的颜色。 

## 工作示例

 ### 示例 1

 输入：```
4 8
2 2 2 2
```初始堆：

 | 步骤| 提取| 剩余堆度 | 新边缘 |
 | ---| ---| ---| ---|
 | 1 | 1（2）| 2,2,2 | (1,2), (1,3) | (1,2), (1,3) |
 | 2 | 4（2）| 1,1 | (4,2), (4,3) | (4,2), (4,3) |
 | 3 | 无 | 空 | 完成 |

 产生的掉期：```
1 2
1 3
4 2
4 3
```每个玩家恰好出现两次，与他们最初的牌数相匹配。 

该迹线直接显示了度数解释。 一旦玩家的度数归零，他们就不会再出现，因为他们的卡牌都已被放弃。 

### 示例 2

 输入：```
3 3
1 1 1
```总度数为：$$1 + 1 + 1 = 3$$这很奇怪。 

| 步骤| 检查 | 结果 |
 | ---| ---| ---|
 | 1 | 总和 % 2 == 1 | 不可能|

 输出：```
No
```此示例显示奇偶校验条件。 每次交换都会恰好删除两张剩余的牌，因此奇数总数永远不会达到零。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(s log n) | 每条边都会引发堆操作 |
 | 空间| O(s) | 存储堆和答案边 |

 交换次数等于$$\frac{\sum a[i]}{2}$$这最多是`2 * 10^5`。 每个堆的操作成本`O(log n)`，因此总运行时间很容易符合限制。 

内存使用也是安全的，因为答案本身最多可以包含`2 * 10^5`互换。

 ## 边缘情况

 考虑输入：```
3 3
1 1 1
```该算法立即检查总度数和的奇偶性。 由于总和是奇数，因此打印`No`在任何堆处理开始之前。 这可以避免构造永远无法终止的部分交换序列。 

现在考虑：```
3 4
4 0 0
```堆最初只包含一个具有度数的顶点`4`。 当我们弹出它时，堆的剩余顶点为零。 条件```
deg_u > len(pq)
```变为真，因为`4 > 0`。 该算法正确地得出结论，玩家 1 不能与四个不同的伙伴交换。 

一个更微妙的有效案例是：```
4 4
2 1 1 0
```初始堆：```
(2,1), (1,2), (1,3)
```玩家 1 连接到玩家 2 和 3。他们的度数变为零，并且堆被清空。 

构建的互换：```
1 2
1 3
```玩家 1 放弃了自己的两张牌，而玩家 2 和 3 各放弃了一张。 没有一对重复，因此不会收到重复的颜色。 

最后，考虑：```
5 8
2 2 2 2 0
```孤立的玩家不会造成任何问题。 堆只是忽略零度顶点。 该算法在四名活跃玩家之间建立一个循环，满足所有要求，而无需触及玩家 5。
