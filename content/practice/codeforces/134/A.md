 ## 解决方案
 ## 问题理解

 我们得到一个正整数数组。 对于每个位置，我们删除该元素并计算剩余数字的算术平均值。 我们必须找到移除值本身恰好等于该平均值的所有位置。 

假设数组是`[1, 2, 3, 4, 5]`。 如果我们删除`3`，剩下的数字是`1, 2, 4, 5`。 他们的总和是`12`，他们的平均值是`12 / 4 = 3`，所以索引`3`是有效的。 

数组大小可以达到`2 · 10^5`，这立即排除了任何从头开始重新计算每个位置总和的解决方案。 二次算法的执行情况约为`4 · 10^10`最坏情况下的操作，远远超出了1秒的时间限制。 我们需要接近线性时间的东西。 

值本身很小，最多`1000`，但这并不足以证明任何昂贵的嵌套循环的合理性。 瓶颈在于元素的数量，而不是数字的大小。 

一个容易犯的错误是使用浮点算术求平均值。 条件是完全相等，浮点比较可能会引入精度问题。 一切都可以用整数来处理。 

考虑这个输入：```
3
1 2 3
```如果我们删除`2`，剩余的平均值为`(1 + 3) / 2 = 2`，所以索引`2`是有效的。 

粗心的实现可能会将平均值计算为浮点数并直接进行比较，这是不必要且有风险的。 

另一个微妙的情况是当剩余的总和不能被整除时`n - 1`。```
4
1 1 1 2
```对于最后一个元素，剩余平均值为`(1 + 1 + 1) / 3 = 1`， 所以`2`无效。 

对于第一个元素，剩余平均值为`(1 + 1 + 2) / 3 = 4/3`，它不是整数。 由于数组元素是整数，因此该索引不起作用。 忘记整除性检查可能会产生错误的答案。 

所有值都相等的数组也值得检查：```
5
7 7 7 7 7
```每个索引都是有效的，因为删除任何索引`7`平均留下`7`。 

## 方法

 最直接的解决办法就是暴力破解。 对于每个索引`i`， 消除`a[i]`，计算所有剩余元素的总和，除以`n - 1`，并检查结果是否等于`a[i]`。 

蛮力是正确的，因为它遵循字面的定义。 问题在于重复求和。 计算剩余金额需要`O(n)`一个职位的时间，我们对所有人重复这一点`n`职位、给予`O(n^2)`总的复杂性。 

和`n = 2 · 10^5`，这大致变成：```
2 · 10^5 × 2 · 10^5 = 4 · 10^10
```操作，这太慢了。 

关键的观察是，如果我们已经知道数组总和，则可以立即获得剩余元素的总和。 

让：```
total = sum of all elements
```如果我们删除`a[i]`， 然后：```
remaining_sum = total - a[i]
```条件变为：```
a[i] = (total - a[i]) / (n - 1)
```我们没有实际将平均值计算为浮点值，而是重新排列了方程：```
a[i] × (n - 1) = total - a[i]
```或等价：```
a[i] × n = total
```这就是整个问题简化为一个简单的等式。 

现在，每个位置都可以在恒定时间内独立检查，从而给出`O(n)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取数组并计算其总和。 

总和让我们可以得出在恒定时间内删除任何位置后剩余元素的总和。 
2. 创建一个空列表`answer`存储有效的索引。 

我们必须按升序输出索引，因此从左到右扫描自然会保留所需的顺序。 
3. 对于每个索引`i`，检查是否：```
a[i] × n == total
```这直接来自于重新排列平均条件。 
4. 如果条件成立，则追加`i + 1`到答案列表。 

该问题使用从 1 开始的索引，而 Python 数组使用从 0 开始的索引。 
5. 打印有效索引的数量。 
6. 打印索引本身。 

### 为什么它有效

 对于一个索引`i`为有效，该值`a[i]`必须等于所有其他元素的平均值：```
a[i] = (total - a[i]) / (n - 1)
```两边同时乘以`n - 1`给出：```
a[i](n - 1) = total - a[i]
```将术语放在一起：```
a[i]n = total
```该算法准确地检查每个索引的这个条件。 由于该方程在数学上等价于原始定义，因此每个报告的指数都是正确的，并且每个正确的指数都被报告。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    total = sum(a)

    ans = []

    for i in range(n):
        if a[i] * n == total:
            ans.append(i + 1)

    print(len(ans))

    if ans:
        print(*ans)

solve()
```第一步计算一次总和。 这是消除重复求和的需要的关键优化。 

条件：```
a[i] * n == total
```是原始平均方程的重新排列版本。 使用整数运算可以避免所有浮点问题。 

答案列表存储从 1 开始的索引，因为这是语句所需要的。 忘记了`+1`是一个常见的差一错误。 

仅当至少有一个有效索引时才打印第二输出行。 该问题允许在答案计数为零时省略该行或打印空行。

输入：```
2

```总和是`6`。 

对于这两个职位：```

```这验证了该公式对于允许的最小值也能正确工作`n`。
