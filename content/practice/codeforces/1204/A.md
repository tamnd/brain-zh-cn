 ## 解决方案
 ## 问题理解

 火车有时发车$$1, 4, 16, 64, \dots$$这正是 4 的幂。给定时间$s$，我们需要计算有多少个出发时间严格小于$s$。 

不寻常的部分是$s$不以十进制给出。 相反，它以不带前导零的二进制字符串形式给出，并且其值可以大到$2^{100}-1$。 普通的 64 位整数不足以存储所有可能的值。 

该约束立即表明我们应该避免将整个数字转换为标准整数类型。 二进制表示最多包含 100 位，因此任何在线性时间内直接处理字符串的解决方案都足够快。 

关键的观察结果是每趟火车的出发时间都是 4 的幂：$$4^k = 2^{2k}.$$在二进制中，4 的幂如下所示：$$1,\ 100,\ 10000,\ 1000000,\dots$$每个都恰好有一个设置位，并且该位位于偶数位置。 

一些边缘情况很容易被错误处理。 

考虑：```
1
```时间正是$1$。 由于出发必须严格在$s$，还没有火车开走。 答案是：```
0
```计算小于或等于 4 的幂的解决方案$s$会错误地返回 1。 

考虑：```
100
```这是$4$以十进制表示。 时间只有火车$1$出发较早，所以答案是：```
1
```再次，使用$\le$而不是$<$会产生 2.

 另一个微妙的情况是：```
101
```这是$5$。 出发时间为$1$和$4$两者都较早，所以答案是：```
2
```尽管两个数字具有相同的二进制长度，但这与前面的示例不同。 我们必须区分 4 的纯幂和相同位长度的更大数。 

## 方法

 一个直接的暴力破解想法是重复生成 4 的幂：$$1,4,16,64,\dots$$并计算有多少个小于$s$。 自从$s < 2^{100}$，大约只有 50 个 4 的相关幂。如果我们先将二进制字符串转换为一个大整数，这种方法实际上已经足够快了。 

更有趣的解决方案完全避免转换数字。 

出发时间是4的幂，正是数字$2^{2k}$。 假设二进制表示为$s$有长度$L$。 

二进制长度严格小于的每个 4 的幂$L$自动小于$s$。 它们的长度是$$1,3,5,\dots$$因为$2^{2k}$有二进制长度$2k+1$。 

此类权力的数量为$$\left\lfloor \frac{L-1}{2} \right\rfloor.$$剩下的就是确定 4 的幂是否具有相同的二进制长度$s$也应该计算在内。 

对于长度为二进制的字符串$L$，那个功率是$$2^{L-1}.$$只有当它是 4 的幂时$L-1$是偶数，意思是$L$很奇怪。 

如果$L$是奇数并且$s$严格大于二进制字符串$$1\underbrace{00\dots0}_{L-1\text{ zeros}},$$那么 4 的附加幂也小于$s$并且必须被计算在内。 

这将整个问题简化为检查二进制字符串本身。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(L) | O(1) | O(1) | 已接受 |
 | 最佳 | O(L) | O(1) | O(1) | 已接受 |

 这里$L \le 100$是二进制字符串的长度。 

## 算法演练

 1.读取二进制字符串$s$。 
2.让$L$是它的长度。 
3. 计算二进制长度严格小于的所有 4 的幂$L$。 

这个数字是：$$\left\lfloor \frac{L-1}{2} \right\rfloor.$$4.如果$L$是偶数，4 的幂没有二进制长度$L$，因此输出当前计数。 
5. If$L$是奇数，比较$s$二进制字符串由前导组成`1`后面只有零。 

该字符串代表$2^{L-1}$，具有长度的 4 的唯一幂$L$。 
6.如果$s$严格大于该字符串，则为答案加一。 
7. 输出结果。 

为什么它有效：

 4 的每个幂都对应于一个二进制数，该数在偶数指数处恰好有一个设置位。 在二进制长度小于的数字中$L$，所有这些幂都自动小于$s$，它们的计数正好是$\lfloor (L-1)/2 \rfloor$。 什么时候$L$很奇怪，还有一个候选者，即$2^{L-1}$。 当严格小于时应精确计数$s$。 该区间内不能存在其他 4 的幂，因为 4 的幂每次增加两位指数。 因此，该算法准确地计算了时间之前的出发次数$s$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

ans = (n - 1) // 2

if n % 2 == 1:
    if s != "1" + "0" * (n - 1):
        ans += 1

print(ans)
```第一部分计算 4 的幂数，其二进制长度严格小于输入的长度。 

表达式`(n - 1) // 2`直接来自计算奇数长度：$$1,3,5,\dots < n.$$唯一剩下的问题是是否应该包含具有相同二进制长度的 4 的幂。 只有当这样的力量存在时`n`很奇怪。 

对于奇数长度`n`，相关幂正是字符串：```
1000...000
```和`n-1`零。 如果输入等于该字符串，则出发时间不严格早于`s`，所以我们不添加它。 任何其他相同长度的二进制字符串都更大，这意味着应该计算 4 的幂。 

不需要整数转换，这避免了对数字大小的任何担忧。

import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

 ## 边缘情况

 考虑输入：```
1
```该算法计算`n = 1`和`ans = 0`。 由于字符串等于`1`，不添加额外计数。 结果是：```
0
```这正确地处理了出发必须严格在到达时间之前的事实。 

考虑输入：```
100
```这里`n = 3`，所以初始计数为`(3 - 1) // 2 = 1`。 同样长度的电源线也是`100`。 因为它们是相等的，所以不计算额外的火车。 答案依然是：```
1
```这可以防止准确计算出发时间的常见错误$s$。 

考虑输入：```
101
```再次`n = 3`，所以初始计数为1。相同长度的幂串为`100`，且输入量较大。 添加一列额外的列车，给出：```
2
```这说明了为什么必须以不同于严格更大的方式对待平等。 

考虑输入：```
11
```长度均匀。 4 的幂不能具有二进制长度 2，因为 4 的幂始终具有奇数二进制长度。 该算法立即返回：```
0
```与现实相符，因为$3$小于第一个相同长度的候选者$4$。
