 ## 解决方案

 ## 问题理解

 游戏在一排桩上进行。 在每次移动中，只有最左边仍然包含石子的堆很重要，并且玩家可以从该堆中移除任意正数的石子。 一旦一堆空了，就以同样的方式继续玩下一堆。 玩家轮流轮流，因所有堆都空而无法移动的玩家失败。 

虽然这看起来像多个独立的堆，但最左边的限制将其变成了一个单一的演变序列，其中堆被一个接一个地耗尽，并且每次耗尽可能会也可能不会“翻转”战略局势，具体取决于该堆内花费了多少步。 

输入由几个独立的游戏组成。 对于每场比赛，我们必须决定第一个玩家在最佳发挥下是否强制获胜。 

这些约束允许所有测试用例中的总桩数最多为十万个。 这立即排除了任何单独处理每个棋子甚至每个动作的模拟。 任何解决方案都必须在线性时间内扫描每个测试用例，因为二次或每次移动推理将超出限制几个数量级。 

当所有堆都只包含一颗石头时，就会出现一种微妙的边缘情况。 在这种情况下，每一步都会完全清空一堆，因此游戏简化为跨堆的简单交替。 例如，对于`[1, 1, 1]`，第一个玩家获胜，而对于`[1, 1, 1, 1]`，第二个玩家获胜。 天真的直觉可能会错误地关注棋子的总平价，但这并不是游戏的主宰因素。 

当序列早期存在大于一个的堆时，会出现另一个重要的边缘情况。 例如，在`[2, 5, 4]`，第一个玩家通过控制第一堆的减少方式立即获胜。 但是，如果第一个较大的堆出现较晚，例如`[1, 1, 2, ...]`，奇偶校验的变化取决于其位置，而不仅仅是其值。 

“全部”与“第一个非一堆”这两种行为是唯一重要的结构情况。 

## 方法

 暴力方法会逐步模拟游戏。 我们将维护当前的堆索引并反复从中减去，交替玩家，直到所有堆都空了。 在最坏的情况下，一堆石头最多可容纳 10 亿颗石头，这意味着单个测试用例可能需要最多$10^9$的操作，远远超出了可行的限度。 即使我们只模拟桩的过渡，我们仍然要冒每次移动每桩的线性工作的风险，这是不必要的。 

关键的观察结果是，在一堆石头中，石头的确切数量并不重要，重要的是它是否等于一或大于一。 如果一堆的大小恰好为 1，则它是强制的：无论谁在上面玩，都会将其移走并立即将控制权传递给下一堆。 如果一堆的大小大于一，当玩家第一次到达它时，该玩家可以控制在它变成一大小之前发生多少内部移动，从而有效地决定“回合平价”是否在该边界翻转。 

这将整个游戏简化为找到第一堆不等于 1 的游戏。 如果所有桩都是一堆，则结果仅取决于存在多少这样的强制移动。 否则，第一个非单堆的位置决定第一个玩家是否可以保持控制或失去控制。 

因此，我们将问题简化为每个测试用例一次线性扫描。

 ## 算法演练

 1. 从左到右扫描一堆石头，检查每堆是否正好有一颗石头。 这可以确定我们是否仍处于不存在决策的被迫迁移阶段。 
2. 在第一堆尺寸大于 1 的地方停止。 这个位置很关键，因为它是玩家控制游戏在一堆中停留多长时间的第一个点。 
3. 如果索引 i 处存在这样的一堆，则根据 i 是奇数还是偶数来确定获胜者。 如果 i 是奇数，则第一个玩家获胜，因为他们以有利的回合平价到达第一个可控堆。 如果 i 是偶数，则第二个玩家继承该优势。 
4. 如果不存在这样的一堆，意味着每堆都只有一颗石子，则根据 n 计算获胜者。 如果 n 是奇数，则第一个玩家获胜，因为他们做出了最后一步。 如果 n 为偶数，则第二个玩家执行最后一步并获胜。 

奇偶性本身就足够的原因是，每一堆大小都恰好消耗一次移动并翻转玩家。 只有尺寸大于一的第一堆可以通过引入可控段来打破这种强制交替，并且它的位置决定了平价优势是保留在第一玩家还是转移。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        idx = -1
        for i, v in enumerate(a):
            if v > 1:
                idx = i
                break
        
        if idx == -1:
            out.append("First" if n % 2 == 1 else "Second")
        else:
            out.append("First" if idx % 2 == 0 else "Second")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案读取每个测试用例并对数组执行一次传递。 该循环搜索第一个不等于 1 的堆，并存储其索引。 如果不存在，则决定仅取决于堆的数量是否为奇数。 否则，由指数平价决定胜负。 

关键的实现细节是从零开始的索引。 该推理在概念上使用从 1 开始的位置，因此代码直接对从 0 开始的索引应用偶数或奇数检查，无需调整。

 ## 边缘情况

 当所有堆都恰好包含一颗石子时，游戏就变成了跨堆移动的严格交替。 用于输入`[1, 1, 1, 1]`，算法检测到没有大于 1 的堆，因此它回退到检查 4 的奇偶校验并正确返回 Second。 强制移动的顺序确保第二个玩家做出最后的移动。 

当第一堆本身大于一时，比如`[7, 1, 1]`，扫描在索引 0 处停止。由于索引 0 是偶数，因此算法返回 First。 在这种情况下，第一个玩家永远不会失去对奇偶性的控制，因为在决策点之前没有强制的单石链。 

当后面出现非一堆时，比如`[1, 1, 1, 5, 1]`，扫描在索引 3 处停止。算法返回 First，因为 3 在从零开始的索引中是奇数，这意味着第二个玩家到达第一个可控堆并且奇偶校验会针对他们进行移位。
