 ## 解决方案
 ## 问题理解

 我们得到了一张包含最多 100 个城市的有向图。 一些对城市之间有固定距离的单向道路，每个城市还拥有一匹马。 马有两个属性：它在变得无法使用之前可以行驶的最大总距离，以及恒定的速度。 

旅行者使用该城市的马从某个城市出发。 每当到达一个城市时，他们可以继续使用当前的马匹，也可以立即切换到当前城市的马匹。 一旦马被使用，它的剩余耐力就会随着使用时行驶的距离而永久减少。 目标是回答多个独立查询，询问两个城市之间的最短旅行时间。 

关键的相互作用是时间取决于距离和当前选择的马，因为在边缘上花费的时间等于边缘距离除以当前使用的马的速度，但耐力约束限制了该马可以继续使用多远。 

约束足够小$N \le 100$，每个测试用例最多可以有 100 个查询。 这立即表明全对或多源最短路径结构是合理的。 然而，国家不仅仅是一座城市，还隐含着目前正在使用的马，这使得朴素的最短路径建模变得复杂。 

用 Dijkstra 独立对待每个城市的天真尝试失败了，因为到达一个城市并不能完全描述你所在的州。 两次到达同一个城市，剩余耐力不同，或者当前的马匹不同，可能会导致完全不同的未来可能性。 

当一匹更强的马在实践中表现更差时，就会出现第二个微妙的失败情况：提前切换可能会提供更高的速度，但剩余的耐力太少，无法到达有用的下一个城市，从而迫使额外的切换。 这使得贪婪的局部决策不正确。 

## 方法

 蛮力观点是将每个状态视为由当前城市、当前马匹和剩余耐力组成的三元组。 在这种状态下，如果耐力允许，则可以遍历每条外出道路，其成本等于距离除以速度。 到达某个节点后，我们可以选择切换到该城市的马，将耐力重置为该马的全部能力。 

这个模型是正确的，但尺寸立即爆炸。 每个城市可以组合多种可能的剩余耐力值，原则上是连续的。 即使离散到有意义的断点，转换仍然会非常大。 扩展状态上的直接 Dijkstra 很容易变成$O(N^2 \cdot E)$，这太慢了。 

关键的结构洞察是我们永远不需要明确地跟踪“还剩下多少耐力”。 重要的只是我们当前使用的马的身份以及使用特定马到达每个城市的最佳时间。 

一旦我们修复了一匹马，运动就变成了一个带有加权边缘的标准最短路径问题，但有一个限制：我们不能让那匹马穿过比它的耐力更多的总距离。 这表明了一个两级DP：对于每种可能的出发马选择，计算到所有节点的最佳旅行时间，同时允许在到达节点时进行切换。 

我们没有将耐力视为连续状态，而是观察到耐力仅沿着使用单个马段的路径消耗。 因此问题就变成了：对于每对城市$u, v$，如果我们最后一次改用马，最好的时间是什么时候$u$在某个时刻，然后使用那匹马旅行，直到可能在中间节点再次切换。 

这导致了一个标准的松弛结构：我们在城市上维护一个距离数组，并且转换对应于在整个路径段中使用特定的马，直到再次切换。 正确的组织方式是对城市进行类似弗洛伊德式的放松，但权重取决于出发的马。 

具体来说，我们仅根据距离（忽略马）预先计算所有对的最短距离，然后使用第二个 DP，其中每个状态代表使用特定马作为分段的活跃马的最佳时间。 因为$N \le 100$，我们可以负担得起$O(N^3)$风格解决方案。 

我们运行了两次经过修改的 Floyd-Warshall：首先是原始距离，然后是每匹马限制的时间。 对于作为马匹起源的每个城市，我们模拟使用该马前往所有可到达的城市，以距离除以速度来累积时间，并且仅在累积距离不超过耐力的情况下才允许过渡。 这可以通过跟踪最佳时间同时遵守每个起始节点的距离上限来嵌入到 Floyd 中。 

更简洁的公式是预先计算所有对的最短距离，然后针对每个城市$i$，计算最短行程时间$i$致所有人$j$使用马$i$具有按距离可行性排序的中间节点上的 DP。 最后，我们在马的选择上采用弗洛伊德式的组合：在任何城市，我们都可以切换到它的马并继续。

 ## 算法演练

 我们将解决方案分为两层：计算每匹马的可用行程，然后在全局范围内结合换马决策。 

1. 在原始距离图上使用 Floyd-Warshall 计算所有城市对之间的最短路径距离。 这给出了忽略马匹的任何两个城市之间的最小距离，这是有效的，因为使用更多的边对耐力的使用永远没有好处。 
2. 对于每个城市$i$，将其马视为主动车辆。 我们计算最佳出行时间$i$到每个城市$j$，在总行驶距离的限制下$i$不超过$E_i$，以及每个单位距离的成本$1 / S_i$时间。 
3. 为了有效地计算，我们使用预先计算的距离矩阵。 对于马$i$， 如果$dist[i][j] \le E_i$，然后达到$j$直接来自$i$有马$i$成本$dist[i][j] / S_i$。 这是最好的选择，因为任何使用额外中间城市的路径只会增加总距离。 
4. 将其存储为矩阵$time[i][j]$， 在哪里$time[i][j]$是最快的时间$i$到$j$如果我们致力于马$i$对于该部分。 
5.现在允许在中间城市换马。 我们随着时间的推移计算第二次弗洛伊德式松弛，其中对于任何中间城市$k$，我们可以从$i \to k$使用马$i$，然后切换到马$k$并继续$j$。 过渡是：$$time[i][j] = \min(time[i][j], time[i][k] + time[k][j])$$6. 关闭后，回答每个查询$u, v$直接来自$time[u][v]$。 

### 为什么它有效

 任何有效的旅程都可以分解为多个片段，其中一匹马在转换之间连续使用。 每个这样的部分都从选择该马的某个城市开始。 在一段内，最短的可用路线始终是最短距离的路径，因为速度和耐力仅取决于总距离，而不取决于路径结构。 第二个 Floyd 步骤以所有可能的顺序将这些片段正确地缝合在一起，确保表示每个有效的马开关序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N, Q = map(int, input().split())

        E = [0] * N
        S = [0] * N
        for i in range(N):
            E[i], S[i] = map(int, input().split())

        dist = [[INF] * N for _ in range(N)]
        for i in range(N):
            row = list(map(int, input().split()))
            for j in range(N):
                if row[j] != -1:
                    dist[i][j] = row[j]
            dist[i][i] = 0

        for k in range(N):
            for i in range(N):
                if dist[i][k] == INF:
                    continue
                dik = dist[i][k]
                for j in range(N):
                    if dist[k][j] == INF:
                        continue
                    nd = dik + dist[k][j]
                    if nd < dist[i][j]:
                        dist[i][j] = nd

        time = [[INF] * N for _ in range(N)]
        for i in range(N):
            for j in range(N):
                if dist[i][j] <= E[i]:
                    time[i][j] = dist[i][j] / S[i]
            time[i][i] = 0.0

        for k in range(N):
            for i in range(N):
                for j in range(N):
                    if time[i][k] + time[k][j] < time[i][j]:
                        time[i][j] = time[i][k] + time[k][j]

        out = []
        for _ in range(Q):
            u, v = map(int, input().split())
            out.append(str(time[u - 1][v - 1]))

        print(f"Case #{tc}: {' '.join(out)}")

if __name__ == "__main__":
    solve()
```该实现首先计算所有对的最短距离，以将任意道路路径折叠成单个有效边缘。 这是必要的，以便耐力检查变得简单比较$E_i$。 之后，`time`矩阵使用每匹马作为固定速度资源来编码最佳直接旅行。 

第二个三环是关于旅行时间的经典弗洛伊德-沃歇尔（Floyd-Warshall），它编码了在任何城市换马的能力。 每次放松都对应于完成前往中间城市的旅行，在那里换马，然后继续。 

必须小心浮点除法，因为所有答案都是实值。 使用 Python 浮点数就足够了$10^{-6}$宽容。

 ## 边缘情况

 关键的边缘情况是存在直接边缘但与多跳最短路径相比不是最佳的。 如果不首先运行 Floyd-Warshall，人们可能会由于局部较大的边权重而错误地拒绝可行的长路线。 预处理可确保所有耐久性检查均在真正的最短距离上执行。 

另一个极端情况是一座城市的马速度极高，但耐力却很低。 天真的贪婪方法总是会选择它并立即无法达到任何有意义的目标。 DP 过度切换通过评估完整的切换序列而不是提前提交来避免这种情况。 

最后，当长链累积除法结果时，可能会出现浮点精度问题。 通过将路径折叠为单个距离值来保持较小的操作数量，可以防止过多的累积误差。
