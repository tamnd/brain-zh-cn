 ## 解决方案
 ## 问题理解

 我们给出了每日油价序列，我们想要检查长度至少为 3 的每个连续子数组。 对于每个这样的部分，我们都会查看其中日常差异的顺序。 这些差异被视为一个小的时间序列，描述了价格在细分市场内的变动情况。 

根据这些差异，我们计算出两个统计数据。 第一个是平均差，它只是连续变化的平均值。 第二个是这些相同变化的标准差。 然后，通过比较平均值与变异性的大小来对分段进行分类：我们检查平均变化是否主导标准差至少一个 P 因子，并使用单独的符号条件确定趋势是正还是负。 

如果某个细分满足正向趋势或负向趋势的不等式，则该细分对答案有贡献。 我们必须计算每个类别有多少个细分市场。 

约束 d ≤ 3000 清楚地表明，所有子段的二次或近二次枚举已经是边界，但任何超过段长度的三次方都是不可能的。 然而，真正的困难不仅仅是枚举，而是每个段都涉及差异的浮点统计，并且对每个子数组进行天真的重新计算会引入额外的线性因子，将暴力方法推向大约 O(n^3)，这太慢了。 

第二个微妙的问题是数值稳定性。 该问题明确允许 P 中的小扰动而不改变答案，这表明派生表达式的直接浮点比较是可以接受的，但强烈建议将代数重排为更稳定的二次形式。 

重要的边缘情况：

 一种边缘情况是段中的所有值都相同。 那么所有差异都为零，因此平均值和标准差都为零。 该问题指出，如果 A = 0，则即使 D = 0，也不存在趋势，因此必须从两个计数中排除此类段。 仅检查不等式而不处理 A = 0 的幼稚实现会错误地将它们分类为对两个符号都有效。 

另一个边缘情况是单调序列。 例如，严格递增序列产生 D = 0。如果 A > 0，则应算作任何幂的正趋势。 粗心的实现可能会错误地除以零或由于零方差而丢弃。 

最后，非常小的段（长度为 3）表现不同，因为方差计算的样本非常少，并且前缀处理中的逐一错误经常出现在这里。 

## 方法

 强力解决方案考虑每个子数组，计算其中的所有差异，然后直接计算平均值和标准差。 对于长度为 L 的固定子数组，计算其统计数据需要 O(L)，并且有 O(n^2) 个子数组，总时间为 O(n^3)。 当 n = 3000 时，这大约是 270 亿次操作，这是不可行的。 

我们可以通过观察均值和方差仅取决于差值的简单相加量来改进这一点。 如果我们定义差值数组 b[i] = c[i+1] − c[i]，则对于任何段 [l, r]，所需的统计量仅取决于 b[l..r−1] 上的和以及同一范围内的平方和。 

在预处理前缀和之后，这会将每个子数组的求值减少到 O(1)。 关键的转变是认识到标准差可以完全通过平方和和总和来表达，从而避免重新计算。 一旦重写，比较平均值和标准差的条件就变成只涉及前缀和值的不等式。 

因此，问题简化为在恒定时间内检查所有 O(n^2) 子数组。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) | O(n^3) | O(1) | O(1) | 太慢了 |
 | 前缀总和大于差| O(n^2) | O(n^2) | O(n) | 已接受 |

 ## 算法演练

 我们根据差异重写问题。 设 b[i] = c[i+1] − c[i]，i 从 1 到 d−1。 

1. 构建前缀和 S[i] = b[1..i] 之和，前缀平方 Q[i] = b[1..i]^2 之和。 这允许恒定时间范围查询。 
2. 对于原数组中长度至少为3的每个子数组[l, r]，考虑其差值范围[l, r−1]。 令 k = r − l，因此有 k 个差异。 
3. 计算该范围内的差值总和，即 sumB = S[r−1] − S[l−1]。 平均值为 A = sumB / k。 
4. 计算平方和 sumB2 = Q[r−1] − Q[l−1]。 
5. 方差乘以 k 表示为 k * D^2 = sumB2 − (sumB^2 / k)。 这避免了显式计算偏差。 
6. 比较 A 和 D，不求平方根。 由于我们只需要 A / D ≥ P 或 A / D ≤ −P，因此我们仔细求平方并分离符号情况：

 如果 sumB = 0，则 A = 0，我们直接拒绝该段。 

否则计算等价于 |A| 的平方不等式 ≥ P * D，但分别保留正趋势和负趋势的符号。 
7. 如果 A > 0 并且条件成立，则增加肯定答案。 如果 A < 0 并且条件成立，则增加否定答案。 

关键思想是一切都简化为前缀和的二次形式，因此每个子数组检查的时间复杂度为 O(1)。 

为什么它有效：

 趋势定义中使用的每个统计量仅是段内差异序列的一阶矩和二阶矩的函数。 这些矩是在范围内相加的，因此前缀和可以充分表征它们。 从方差定义到平方和的转换消除了对每个元素迭代的依赖，最终的不等式仅取决于这些聚合值的代数组合。 由于使用这些聚合上的精确算术对每个段进行一次精确评估，因此除了可忽略不计的浮点错误之外，不会对任何有效段进行错误分类，而问题陈述明确容忍了该错误。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    d, P = input().split()
    d = int(d)
    P = float(P)

    c = list(map(int, input().split()))
    n = d

    if n < 3:
        print("0 0")
        return

    b = [c[i+1] - c[i] for i in range(n - 1)]

    m = n - 1
    S = [0.0] * (m + 1)
    Q = [0.0] * (m + 1)

    for i in range(m):
        S[i+1] = S[i] + b[i]
        Q[i+1] = Q[i] + b[i] * b[i]

    pos = 0
    neg = 0

    for l in range(n):
        for r in range(l + 2, n):
            k = r - l
            sumB = S[r] - S[l]
            if sumB == 0:
                continue

            sumB2 = Q[r] - Q[l]

            mean_num = sumB
            # variance numerator: k*D^2 = sumB2 - sumB^2/k
            # we compare |A| >= P * D carefully without sqrt:
            # A^2 >= P^2 * D^2
            # (sumB^2 / k^2) >= P^2 * ((sumB2/k) - (sumB^2/k^2))

            left = sumB * sumB
            right = P * P * (sumB2 * k - sumB * sumB)

            if left >= right:
                if sumB > 0:
                    pos += 1
                else:
                    neg += 1

    print(pos, neg)

if __name__ == "__main__":
    main()
```该代码首先将价格转换为差异数组，以便每个分段统计数据都可以相加。 前缀数组 S 和 Q 存储这些差异的一阶矩和二阶矩，从而可以对任何区间进行 O(1) 查询。 

双循环枚举所有有效段。 约束 r ≥ l + 2 确保至少三个原始元素。 对于每个段，我们计算 sumB 和 sumB2，然后应用从 A^2 ≥ P^2 D^2 导出的代数不等式。 我们明确跳过零和情况，以遵守 A = 0 意味着没有趋势的规则。 

一个微妙的点是我们从不直接计算平方根或标准差。 这避免了精度问题，也避免了不必要的浮点运算。
