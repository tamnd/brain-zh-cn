 ## 解决方案
 ## 问题理解

 我们得到一个长度为的隐藏数组$n$，包含来自的数字排列$1$到$n$。 我们无法直接看到数组。 我们与之互动的唯一方法是选择两个位置$i < j$并要求法官比较这些位置的数值。 如果左值大于右值，则法官交换它们并报告发生交换； 否则没有任何变化，法官报告没有发生任何事情。 

目标是将数组转换为恒等排列，即位置$i$必须包含价值$i$对于每一个$i$。 在我们查询之后的任何时候，法官都可能会返回 WIN 而不是比较结果，这意味着数组已经完全排序，我们必须立即停止。 

复杂的是阵列不稳定。 每块之后$2n$查询时，法官秘密地均匀随机选择两个位置并交换它们的值。 这种情况会在没有通知的情况下发生，并且可能会破坏进度。 我们仍然必须保证在 10000 个查询内，当法官检查时，我们最终会在某个时刻达到排序状态。 

限制条件$n \le 50$强烈建议我们可以负担二次甚至三次程序$n$，因为任何一次对数组的完整传递最多都会花费几千次操作。 真正的困难不是效率本身，而是随机腐败下的鲁棒性。 

一个天真的解释是尝试准确地重建排列，然后在心理上模拟排序，但这会失败，因为数组的变化不可预测。 另一个天真的想法是假设没有损坏并运行一次标准排序算法，但在每批随机交换之后，数组再次变得无效，并且我们永远不会可靠地收敛。 

关键的边缘情况是以下情况。 假设在某个时刻，数组已排序，但在随机交换之后，在我们查询任何内容之前，它立即再次变为未排序。 如果我们的算法仅在固定检查点检查完成情况或假设单调改进，则它可能会完全错过获胜时刻或永远不会稳定。 

因此，我们需要一个过程，能够持续不断地强制执行本地顺序，即使在偶尔随机交换之后，数组也会反复被驱回排序顺序。 

## 方法

 暴力策略将尝试在每次损坏事件后恢复整个排列，然后从头开始排序。 这将涉及重复查询许多对以完全推断顺序，从而在每个周期中有效地重建数组。 即使我们可以识别出排列$O(n \log n)$比较，每次之后重复此操作$2n$操作会导致最坏情况下的大约爆炸$O(\text{cycles} \cdot n \log n)$，并且由于所需的损坏周期数没有限制，因此此方法不能保证在 10000 个查询内完成。 

重要的观察是我们不需要全局重建排列。 每个查询都已经为我们提供了两个位置之间正确的本地排序。 如果我们重复地强制相邻位置的一致性，即使在轻微的扰动下，数组的行为也会像连续排序一样。 

这自然会导致基于比较的排序网络风格的方法，特别是类似于冒泡排序或奇偶转置排序的重复相邻交换。 每次比较都会强制执行局部不变量：每当我们检测到反转时，较小的值向左移动，较大的值向右移动。 即使随机交换引入了新的反转，重复扫描也会再次删除它们。 

自从$n$最多 50，相邻校正成本的完整传递$O(n)$操作，并且重复此类传递有限次数很容易满足 10000 次操作预算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个腐败周期的全面重建|$O(\infty)$有效|$O(n)$| 太慢/不可靠 |
 | 重复相邻的比较交换过程 |$O(n^2)$运营总计 |$O(n)$| 已接受 |

 ## 算法演练

 我们不维护显式数组。 相反，我们完全依赖使用允许的比较交换操作进行重复的局部修正。 

### 步骤

 1. 使用相邻比较从左到右重复执行完整遍历位置$(i, i+1)$。 每个查询都确保如果较大元素位于较小元素的左侧，则将其交换到正确的方向。 这与冒泡排序的机制相同。 
2.完成一个完整的pass后，立即开始另一个pass。 我们不会在一次传递后停止，因为随机交换可以在数组中的任何位置重新引入反转。 
3. 继续执行这些传递，直到法官对某个询问做出 WIN 响应。 此响应取代了正常的 SWAPPED 或 STAYED 输出，并表明数组当前已完美排序。 
4. 收到WIN后总是立即停止，不打印进一步的操作。 

我们使用相邻比较的原因是它们保证了校正的最大局部性。 在足够的交换传播值之后，任何反转最终都必须显示为相邻反转，并且一旦出现，就可以立即修复。 

### 为什么它有效

 核心不变量是每次比较要么消除局部反转，要么保持局部顺序不变。 虽然随机交换可能会暂时增加反转数量，但每次完整扫描都会严格减少当前相邻或足够接近以进行校正的反转数量。 由于每次反转最终都必须在重复扫描过程中变得相邻，因此该过程会不断地消除系统的无序性。 

由于系统是有限的，并且每次成功的校正都会使数组更接近完全排序的配置，因此除非中断，否则数组会在无数个时刻进行排序。 法官检测到这些时刻之一并输出 WIN，此时我们终止。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(i, j):
    print(i, j, flush=True)
    res = input().strip()
    if res == "WIN":
        sys.exit(0)
    return res

def main():
    n = int(input().strip())
    max_ops = 10000
    used = 0

    while used < max_ops:
        for i in range(1, n):
            if used >= max_ops:
                break
            ask(i, i + 1)
            used += 1

if __name__ == "__main__":
    main()
```该实现遵循最简单形式的奇偶转置思想：重复从左到右相邻比较。 每个查询都会立即发出，如果收到 WIN，我们会立即终止。 

主要的微妙之处在于我们从不尝试存储或重建数组。 由于隐藏的随机交换，任何在本地模拟它的尝试都会与判断不同步。 该程序仍然是纯粹的反应式。 

我们还严格遵守交互协议，刷新每个输出并在获胜后立即停止。

 假设隐藏数组是$[1, 3, 2, 4]$。 

| 步骤| 查询 | 回应 | 数组状态（概念）|

 这表明，当单个反转变得相邻时，它会立即被删除。 

在第 2 步之后，数组已完全排序，法官会在下一次交互时检测到这一点。

| 步骤| 查询 | 回应 | 数组状态（概念）|

跟踪证实，每个反转最终都会被推到相邻比较修复它的位置。

 ## 边缘情况

 一个微妙的边缘情况是，由于随机交换停止在有利的配置中，数组在两个操作之间精确排序。 在这种情况下，算法不需要显式地检测排序性； 它依赖于法官在下一个查询中返回 WIN。 例如，如果数组变为$[1,2,3,4]$在隐藏交换事件之后，下一个比较查询立即触发 WIN 并正确终止。 

另一种情况是，随机交换持续破坏全局秩序的速度比单次修复它的速度要快。 即便如此，每次局部校正在遇到时仍然会消除至少一个反转。 由于每次扫描都会系统地重新检查所有相邻对，因此不会永远未检查任何反演。 最终，在查询时不存在反转的时刻发生，并且 WIN 被触发。
