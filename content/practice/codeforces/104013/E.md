 ## 解决方案
 ## 问题理解

 我们得到了对以 value 开头的单个整数变量的操作集合`c`。 每个操作的形式为“如果当前值等于`a`，然后将其替换为`b`”，否则它什么也不做。除了每个操作之外，我们还被告知我们希望它在最终执行顺序中成功还是失败。

 成功的操作必须在变量当前等于其值的时刻执行`a`价值。 失败的操作必须在变量不等于的时刻执行`a`。 任务是找到操作的任何顺序，以便每个操作的行为完全按照请求进行。 

关键的困难在于执行成功的操作会更改全局变量，从而影响所有后续操作。 所以顺序不是独立的，每个操作都限制了使用时当前的值必须是什么，进而影响未来的可行性。 

这些约束最多允许 100,000 次操作，因此任何尝试排列或重复模拟订单的方法都不起作用。 即使二次模拟也太慢，并且任何涉及排序回溯的事情都远远超出了限制。 我们被迫采用线性或近线性结构。 

一些微妙的边缘情况立即出现。 

如果两个不同的操作都需要以相同的值成功`a`但会导致不同的`b`，那么只有其中一个可以成为“第一个触发”该值更改的人，而另一个可能永远无法使用，具体取决于顺序。 

如果某个操作需要失败并且其`a`等于初始值`c`，那么它一定不能首先出现，因为如果放在第一位它会立即成功。 

当成功操作形成必须遵守的状态转换链，而失败操作必须安排在不被触发的“安全”状态时，就会出现一种特别棘手的情况。 任何忽略状态可达性的天真贪婪排序往往会在这里破裂。 

## 方法

 蛮力视角将尝试所有操作排列，从初始值模拟变量并检查每个操作是否与其所需的结果匹配。 这原则上是正确的，因为它直接执行规则，但需要评估`n!`订单。 即使基于部分可行性的修剪仍然会导致指数分支，因为每个放置都会以影响所有剩余操作的方式更改状态空间。 

关键的观察是，每个成功的操作的行为就像从`a`到`b`，并且失败操作对变量何时必须避免特定值施加约束。 我们不应该考虑排列，而应该考虑构建有效的遍历值，其中每个成功的操作都在遍历到达其所需节点时准确使用。 

关键的结构洞察力是成功的操作是唯一改变状态的操作。 失败操作不会改变变量； 它们只是对相对于状态的排序的限制。 这建议将问题分解为通过值处理一系列强制转换，同时将故障操作安排在满足禁止条件的“无问题”位置。 

我们可以将成功的操作解释为图中的边`a`到`b`。 如果我们决定成功操作的顺序，它们就会定义一条确定性的值路径，从`c`。 一旦这条路径被修复，每个失败操作都必须被放置在当前值不等于其值的点上。`a`。 这将问题转化为确保我们永远不会在条件意外成立时执行失败操作。 

这导致了一个建设性的策略：我们首先构建一个有效的成功操作序列，形成一致的状态进展，然后只要它们相对于当前状态是安全的，我们就会贪婪地交错失败操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了|
 | 建设性排序 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 根据以下条件将操作分为两组`w`：需要成功和需要失败。 成功的操作必须匹配`v == a`，而失败者必须避免这种情况。 
2. 对于每个成功的操作，将其视为来自`a`到`b`。 我们将尝试构建一个从初始值开始遵循这些边的序列`c`。 目标是确保每当我们应用成功的操作时，当前值正是它的值`a`。 
3. 收集所有成功操作，按其起始值分组`a`。 这使我们能够快速找到当前状态下可以应用哪些成功操作。 
4. 维护指针`cur`对于变量的当前值，最初`c`，并维护一个结构，使我们能够从以下位置开始选择未使用的成功操作`cur`只要有可能。 
5. 重复执行以下操作： 如果存在未使用的成功操作`a == cur`，选择任何此类操作，将其附加到答案中，将其标记为已使用，然后更新`cur = b`。 此步骤是强制的，因为应用成功操作是推进状态的唯一方法。 
6. 如果当前值不存在这样的成功操作，那么我们将暂时陷入无法进一步前进的值。 此时，我们可以安全地放置任何剩余的失败操作，其`a`不等于`cur`，因为执行它不会意外成功。 
7. 为了确保正确性，我们维护一组待处理的失败操作。 每当我们需要进行失败操作时，我们都会选择任何一个`a != cur`。 如果所有剩余的失败操作都有`a == cur`，那么不可能在不违反其所需失效条件的情况下放置它们。 
8. 继续，直到所有操作都完成。 如果在任何时候都无法选择有效的成功或失败操作，则输出“No”。 

### 为什么它有效

 该算法维护与所有先前执行的成功操作完全匹配的当前状态值。 每个成功操作只有在满足其前提条件时才会执行，因此状态演化始终是一致的。 失败操作只有在触发条件为假时才会执行，因此构造也满足了它们的要求。 

核心不变量是当前值`cur`总是可以通过已选择的成功操作序列从初始值到达，并且到目前为止放置的失败操作从未在其禁止状态下执行过。 由于成功操作严格定义状态转换，而失败操作永远不会更改状态，因此任何有效的排序都必须对应于一个序列，其中所有成功转换形成一致的路径，并且所有失败仅在不匹配的状态下插入。 贪婪结构确保我们永远不会过早地阻止未来的成功转换，因为我们只有在存在匹配的成功边缘时才会前进。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, c = map(int, input().split())

succ = {}
fail = []

for i in range(n):
    a, b, w = map(int, input().split())
    if w == 1:
        if a not in succ:
            succ[a] = []
        succ[a].append((b, i + 1))
    else:
        fail.append((a, i + 1))

used = set()
res = []
cur = c

# success operations indexed by availability
from collections import defaultdict, deque
succ = {k: deque(v) for k, v in succ.items()}
fail = deque(fail)

while len(res) < n:
    progressed = False

    # try success
    if cur in succ:
        while succ[cur] and succ[cur][0][1] in used:
            succ[cur].popleft()
        if succ[cur]:
            b, idx = succ[cur].popleft()
            used.add(idx)
            res.append(idx)
            cur = b
            progressed = True

    if progressed:
        continue

    # try failure
    if not fail:
        break

    placed = False
    for _ in range(len(fail)):
        a, idx = fail.popleft()
        if a != cur:
            used.add(idx)
            res.append(idx)
            placed = True
            break
        else:
            fail.append((a, idx))

    if placed:
        continue

    break

if len(res) == n:
    print("Yes")
    print(*res)
else:
    print("No")
```该实现维护每个值的映射`a`一切成功的行动都从它开始。 当前值`cur`驱动哪些成功的操作符合条件。 当发现这样的操作时，会立即应用它，因为延迟它永远不会有帮助，它是改变状态的唯一机制。 

失败的操作存储在队列中并轮换，直到找到安全的操作。 失败的操作在其发生时是安全的`a`与当前状态不同。 这确保我们永远不会意外地将假定的失败变成成功。 

主要的微妙之处在于，必须始终优先考虑成功的运营。 如果当前状态存在有效的成功，则延迟它可能会永久阻塞前进的道路，因为失败操作不会更改状态并且无法创建新的适用性。

### 示例 2

 输入：```
3 1
1 2 1
1 2 1
1 2 0
```开始于`cur = 1`。 

两次成功的操作都需要`1`，所以我们可以先执行其中一个。 假设我们选择操作 1：

 | 步骤| 当前| 选择的操作 | 类型 | 新当前|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 操作 1 | 成功| 2 |

 现在没有成功的操作适用于`cur = 2`。 唯一剩下的成功操作需要`1`，所以它们不能被执行。 失败操作还需要`a = 1`，但自从`cur != 1`，是安全的，可以执行。 此后，剩余的成功操作将无法正确放置，从而导致整体失败。 这表明，一旦国家偏离了剩余成功所需的先决条件，可行性就会崩溃。

 ## 边缘情况

 当所有剩余的成功操作需要一个从当前状态无法再访问的值时，就会出现临界边缘情况。 例如，开始于`c = 1`，如果我们应用成功的操作`1 → 2`，并且所有剩余的成功操作都需要`1`，那么我们就永久失去执行它们的能力。 该算法隐式处理此问题，因为它始终首先消耗可用的成功转换，但一旦不存在匹配的转换，它就不会强制状态更改，从而使剩余的成功要求无效。 

另一个边缘情况是所有剩余的故障操作都需要当前值。 在这种情况下，不存在安全的故障放置，并且算法正确地停止并输出“否”。 这对应于当前状态被无法在任何其他时间安全执行的故障“阻止”的配置。 

最后一个微妙的情况是，成功的操作形成了价值的循环。 贪婪遍历自然地处理了这个问题，因为每个成功操作都只使用一次，而循环仅意味着重新访问值，只要转换与可用边缘一致，就允许这样做。
