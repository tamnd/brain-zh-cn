 ## 解决方案
 ## 问题理解

 骑自行车的人正在两个每月自行车租赁计划之间进行选择，我们需要计算每个计划在固定月份内的总成本。 

骑车人每天总共使用自行车`T`分钟。 该时间分为上下班时间和返回时间，但对于该问题，它已经作为单个每日总时间给出。 

第一个计划收取固定月费`a`。 根据该计划，每天有 30 分钟的免费时间。 如果每天使用时间超过30分钟，每增加一分钟就会产生费用`x`。 

第二个计划收取固定月费`b`。 根据该计划，每天有 45 分钟的免费时间。 任何超过 45 分钟的费用`y`每分钟。 

11 月正好有 21 个工作日，假设所有日子的每日模式都相同。 任务是计算所有 21 天内每个计划的总成本。 

输出是两个整数，分别代表第一个和第二个计划下的总成本。 

限制非常小，所有货币价值和`T`最多为 100 或 1440。这立即表明每个计划的任何直接算术就足够了，因为计算是恒定时间的。 不需要大范围的循环或优化技术。 

一个常见的错误源于对“空闲时间”界限的误解。 如果`T`小于或等于免费限额，则额外费用必须为零，而不是负数。 另一个微妙的问题是忘记了超额费用是按天计算的，并且必须乘以 21。 

例如，如果`T = 10`，这两个计划都没有额外费用，答案很简单`(21 * a, 21 * b)`。 不将其钳位为零的简单实现会错误地产生负电荷。 

## 方法

 暴力解释将模拟 21 天中的每一天，并在每一天中迭代超出免费限额的每一分钟以累积成本。 例如，对于每一天，我们可以从第 31 分钟循环到`T`对于第一个计划并添加`x`每分钟。 这工作正常，但内部循环使其变得不必要的冗长。 

在最坏的情况下，`T = 1440`，因此内部循环每天运行大约 1410 次迭代。 在 21 天内，每个计划大约执行 30,000 次操作，这仍然不错，但考虑到结构，完全没有必要。 

关键的观察结果是，每个计划仅取决于超过阈值的分钟数，而不取决于其分布。 一旦我们计算出`max(0, T - 30)`和`max(0, T - 45)`，总成本变成一个简单的线性公式。 这将问题简化为常数时间算术。 

蛮力之所以有效，是因为它直接累积每分钟的成本，但当我们认识到所有超过阈值的分钟的成本都是相同的时，它就会因为过于复杂而失败。 观察结果将每分钟循环折叠为单个乘法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(21·T) | O(21·T) | O(1) | O(1) | 已接受但没有必要 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们使用相同的结构独立计算每个计划。 

1. 读取输入`a, x, b, y, T`。 这些定义了固定成本、每分钟罚款和每日使用情况。 
2. 计算第一个计划的收费分钟数：`over1 = max(0, T - 30)`。 这确保我们永远不会收取免费分钟数。 
3. 将第一个计划的每日总成本计算为`day1 = a + over1 * x`。 固定费用始终每天包含一次。 
4. 乘以21得到每月费用`total1 = 21 * day1`。 这反映了 11 月份的所有工作日。 
5. 使用 45 分钟阈值对第二个计划重复相同的逻辑：`over2 = max(0, T - 45)`。 
6. 计算`day2 = b + over2 * y`进而`total2 = 21 * day2`。 
7. 输出`total1`和`total2`。 

每个步骤都是纯代数的，不需要迭代，因为成本结构与多余分钟数呈线性关系。 

### 为什么它有效

 每个计划都定义了固定的基本费用加上仅适用于超过固定阈值的使用部分的每单位费用。 由于每天都是相同的，因此总成本仅为每日确定性函数的 21 倍。 唯一的决定是是否`T`超过阈值，一旦解决，剩余的计算量与超出的量呈线性关系。 几天之间或一天中的几分钟之间不存在交互，因此将结构折叠成封闭形式的表达式可以保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

a = int(input().strip())
x = int(input().strip())
b = int(input().strip())
y = int(input().strip())
T = int(input().strip())

days = 21

over1 = max(0, T - 30)
day1 = a + over1 * x
total1 = days * day1

over2 = max(0, T - 45)
day2 = b + over2 * y
total2 = days * day2

print(total1, total2)
```该解决方案读取五个整数并立即将它们转换为两个独立的成本公式。 

使用`max(0, ...)`至关重要，因为负超额会错误地减少基本费用。 计算每日成本后乘以21，保持结构干净并降低每日和每月逻辑混合的风险。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    a = int(input().strip())
    x = int(input().strip())
    b = int(input().strip())
    y = int(input().strip())
    T = int(input().strip())

    days = 21

    over1 = max(0, T - 30)
    total1 = days * (a + over1 * x)

    over2 = max(0, T - 45)
    total2 = days * (b + over2 * y)

    return f"{total1} {total2}"

# provided samples
assert run("10\n1\n20\n2\n40\n") == "420 420"

# minimum case: no overage
assert run("0\n0\n0\n0\n1\n") == "0 0"

# boundary at exact thresholds
assert run("5\n2\n7\n3\n30\n") == f"{21*(5)} {21*(7)}"

# second plan dominates due to lower overage
assert run("10\n10\n100\n1\n100\n") == "14700 11550"

# high T case
assert run("1\n1\n1\n1\n1440\n") == str(21*(1 + 1410)) + " " + str(21*(1 + 1395))

 ## 边缘情况

 一种边缘情况是当`T`小于两个阈值。 例如，`T = 10`。 计算`T - 30`和`T - 45`是负数，但应用`max(0, ...)`迫使两个超额都为零，从而导致成本`21 * a`和`21 * b`。 如果没有这个限制，公式就会错误地从基本费用中减去金钱，产生无意义的负总额。 

另一种边缘情况恰好发生在阈值处。 如果`T = 30`，第一个计划必须收取零额外分钟，而不是一分钟或多分钟。 表达式`max(0, 30 - 30)`正确地产生零，确保不会出现意外处罚。 

第三个案例很大`T`接近上限，例如 1440。超额变得很大，但仍然安全地适合整数算术，因为最大乘积为`21 * 1440 * 100`，完全在 32 位限制之内。
