 ## 解决方案
 ## 问题理解

 我们得到一个数组，并要求我们选择它的子序列，这意味着我们可以删除元素，但不能对剩下的元素重新排序。 从所有这些子序列中，我们想要一个有效的多边形边长，这正是至少选择三个元素并且所有所选元素的总和严格大于所选子序列中最大元素的两倍的条件。 

在所有有效子序列中，我们不会最小化或最大化总和。 我们按字典顺序比较子序列，因此我们从第一个位置开始比较：第一个元素较大的序列更好，如果相等，我们移动到下一个位置，依此类推。 

约束足够大，不可能枚举所有子序列，因为有$2^n$其中。 即使检查每个候选人的有效性也太慢了。 因此，任何正确的解决方案都必须贪婪地构造子序列或维护一个可以在每个测试用例的线性或接近线性时间内更新的结构。 

一个微妙的问题是字典顺序以非局部方式与子序列交互。 删除一个小的早期元素可以通过将较大的元素向前拉来增加词典编排值，即使它会减少总和。 这是天真的“获取大元素”或“排序和挑选”方法失败的主要原因。 

## 方法

 强力策略将枚举所有子序列，检查多边形条件，然后按字典顺序选择最佳序列。 从概念上讲，这是可行的，因为它直接评估定义，但它的数组长度呈指数增长，即使对于中等输入大小也无法运行。 

为了取得进展，我们将问题分为两个相互作用的目标。 首先，我们想要一个满足多边形不等式的子序列。 其次，在所有这些子序列中，我们想要字典顺序上最大的输出。 关键的观察结果是，可行性仅取决于三个量：所选的最大元素、所选元素的总和以及所选集合的大小。 元素的顺序不会影响可行性，只有成员资格会影响。 

这提出了一种建设性的方法，我们维护候选集并对其进行调整，直到它变得有效。 字典顺序给出了强烈的偏差：删除较小的元素是更好的选择，因为它不会从早期位置删除较大的值，并且往往会改善移位后的后续比较。 

其核心思想是从所有元素开始，反复删除对可行性和词典质量最无用的元素，即最小的剩余元素，直到满足多边形条件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解子序列 |$O(2^n \cdot n)$|$O(n)$| 太慢了|
 | 贪婪去除最小元素 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们维护当前所选元素的多重集，最初包含数组的所有元素。 我们还维护它们的总和和当前最大值。 

我们反复测试该集合作为多边形是否有效。 条件是集合大小至少为 3，并且总和严格大于最大值的两倍。 

如果条件不成立，我们就删除一个元素。 我们删除的元素始终是当前集合中剩余的最小值。 

如果需要，我们更新总和和最大值，并继续直到条件成立。 

终止后，我们按原始顺序输出剩余元素，因为我们只执行删除，而从未更改相对顺序。 

### 为什么它有效

 多边形条件在特定方向上是单调的：删除一个元素会减少总和并可能减少最大值，但删除最小的元素可以最大限度地减少对不等式的损害，因为它会尽可能少地减少总和，同时尽可能保留最大值。 任何较大元素的删除都会减少最大值或更严重地破坏词典编排最优性。 

由于字典顺序是由最早的剩余位置决定的，因此首先删除较小的值往往会保留较大的早期元素，并且仅在有益时才将较大的元素向前移动。 这确保了每个删除步骤都不会妨碍达到字典顺序上最佳的有效子序列。 

该过程必须终止，因为每一步都会减少元素的数量，并且最终会实现有效性，因为问题保证至少存在一个解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 3:
        print(3)
        print(*a)
        return

    total = sum(a)
    mx = max(a)
    
    import heapq
    heap = a[:]
    heapq.heapify(heap)

    removed = set()
    removed_count = 0

    current_sum = total
    current_max = mx

    while removed_count < n:
        if removed_count + (n - removed_count) >= 3:
            if current_sum > 2 * current_max:
                break

        # remove smallest remaining
        while heap:
            x = heapq.heappop(heap)
            if x not in removed:
                val = x
                break

        removed.add(val)
        removed_count += 1
        current_sum -= val

        if val == current_max:
            current_max = max(v for v in a if v not in removed)

        if n - removed_count < 3:
            break

    ans = []
    for x in a:
        if x not in removed:
            ans.append(x)

    print(len(ans))
    print(*ans)

t = int(input())
for _ in range(t):
    solve()
```此实现维护一个堆，以始终删除最小的可用元素并跟踪不断变化的总和和最大值。 最终的子序列是通过过滤原始数组来重建的，自动保留顺序。 

一个微妙的点是我们从不重新排序元素，因此保证了子序列的有效性。 主循环仅删除元素，直到多边形不等式成立。 

## 工作示例

 考虑一个数组，其中小元素占据早期位置。 最初，所有元素都包括在内，因此总和很大，但最大值相对于总和可能太大。 每次删除都会删除最小的元素，逐渐减少总和，直到不等式成立。 

对于第二个示例，请考虑一个由单个非常大的元素占主导地位的数组。 该算法将首先删除小元素，但如果最大值保持不变，则条件最终会变得更容易满足，因为一旦删除了足够多的小元素，总和与最大值的比率就会提高。 

在这两种情况下，关键的不变量是算法仅删除对满足不等式最不有利的元素。

 ## 边缘情况

 关键的边缘情况是当最大元素与所有其他元素相比非常大时。 在这种情况下，删除小元素不会改变最大值，因此不等式只能缓慢改善。 该算法正确地继续删除最小元素，直到相对于未更改的最大值积累了足够的总和。 

当数组已经接近满足多边形条件时，会出现另一种边缘情况。 这里，算法不执行删除操作，并立即输出完整序列，由于不需要删除，因此保留了字典最优性。 

最后的边缘情况是存在许多重复的小值。 即使值重复，删除策略也会独立处理每次出现的情况，确保总和逐渐减少并且终止仍然正确发生。
