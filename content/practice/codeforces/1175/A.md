 ## 解决方案
 ## 问题理解

 我们得到一个数字$n$和一个参数$k$。 开始于$n$，我们希望使用两个允许的操作达到零：减一，或者如果当前值可以整除$k$，将其替换为除以后的商$k$。 每个操作花费一个步骤，目标是最小化总步骤数。 

这本质上是一个在可整除性允许的情况下逐渐或偶尔大幅跳跃地反复缩小数字的过程。 困难在于除法只是偶尔可用，因此我们不能自由地“贪婪地除法”而不考虑使数字可整除所需的步骤。 

约束条件非常大，$n$和$k$最多$10^{18}$。 这立即排除了任何逐一递减的模拟。 即使是线性扫描$n$是不可能的，因为$10^{18}$操作远远超出了时间限制。 任何有效的解决方案都必须减少对数或接近对数阶段的数量，通常是通过跳过长时间的连续减法。 

一种简单的方法会模拟该过程：如果$n$不能被整除$k$，反复减一，直到可以整除，然后除。 这是正确的，但当$n$很大并且$k$很小。 例如，如果$n = 10^{18}$和$k = 2$，一个简单的模拟会反复减去一以达到偶数，然后除以，多次重复这种模式。 步数与以下成正比$n$，这是不可行的。 

另一个微妙的边缘情况出现时$k = 1$。 除以一不会改变值，因此唯一有意义的运算是减一。 在这种情况下，答案很简单$n$。 任何不防范这种情况的实现都可能永远循环或重复应用无用的除法。 

## 方法

 蛮力策略是始终一步一步地应用最好的可行策略。 在每个状态，如果能被$k$, 划分; 否则减一。 这在局部是合理的，因为除法会快速缩小数字，而减法为将来的除法做准备。 

这可以正确工作，但效率较低，因为减法阶段主导了运行时间。 在最坏的情况下，在每次划分之前，我们可能需要最多$k-1$减法，并且这可以在整个范围内重复多次直到零。 自从$n$取决于$10^{18}$，这会导致无限数量的操作。 

关键的观察是我们永远不需要一一模拟减法。 相反，我们可以直接跳转到最接近的倍数$k$。 如果当前号码是$x$，我们计算$x \bmod k$。 该值准确地告诉我们需要进行多少次减法才能达到可整除的状态。 我们通过一个聚合步骤应用它们。 之后，如果该数字仍然至少为$k$，我们进行除法并继续。 

这将过程转换为一系列大的跳跃，然后是少量的划分，将迭代次数减少到大约$O(\log_k n)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n)$|$O(1)$| 太慢了 |
 | 最佳|$O(\log n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们使用批量减法和偶尔除法的组合来反复减少数量。 

1.如果$k = 1$，唯一有用的举动是减一，所以答案是$n$。 我们立即返回。 这可以避免因不改变任何内容的除法而导致的无限循环。 
2. 虽然$n \ge k$，我们首先计算$r = n \bmod k$。 这告诉我们距离最近的较小倍数有多远$k$。 
3.我们减去$r$一步一步减少$n$到多个$k$，并添加$r$到答案。 这用单个算术跳转取代了许多单元操作。 
4.然后我们划分$n$经过$k$，将答案加一。 这是唯一有效的除法步骤，并且大大减少了幅度。 
5. 我们重复这个过程，直到$n < k$，意味着不再可能进行除法。 
6.最后，我们减去剩余的$n$达到零，添加$n$到答案。 

这样做的原因是，在每个阶段，我们都将最优局部策略转换为精确的成本分解：任何有效的序列最终都必须在除法发生之前删除相同的余数，因此批量支付不会改变最优性。 

### 为什么它有效

 不变的是，在每次迭代之后，我们都考虑了将当前状态带到最近的有效划分点所需的减法运算的确切数量。 由于除法总是在可能的情况下立即执行，并且每次减法都只计算一次，因此任何其他操作顺序都无法降低总成本。 任何最佳路径在划分之前仍然必须“清除”剩余部分，因此对这些操作进行分组可以保留正确性，同时消除低效率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, k = map(int, input().split())
        
        if k == 1:
            out.append(str(n))
            continue
        
        steps = 0
        
        while n >= k:
            r = n % k
            steps += r
            n -= r
            n //= k
            steps += 1
        
        steps += n
        out.append(str(steps))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```代码直接实现了批处理的思想。 模运算计算除法之前需要多少减量。 应用它们后，我们划分一次并继续。 当数字小于时循环终止$k$，此时只剩下减法。 

特殊情况$k = 1$显式处理以避免不必要的循环并正确反映只能递减。

 ## 边缘情况

 当$k = 1$，除法总是可能的，但没用。 该算法显式返回$n$，与只有减法才能减少数字的事实相匹配。 用于输入$n = 5, k = 1$，我们直接输出5。 

当$n < k$，根本没有发生除法。 例如，$n = 7, k = 10$，循环被跳过，答案就是 7，因为我们只减到零。 

什么时候$n$正好可以整除$k$， 例如$n = 100, k = 10$，余数为零，因此我们立即除以，无需额外成本。 该算法在每次划分时正确执行一步，直至终止。
