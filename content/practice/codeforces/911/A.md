[CF 911A - 最近的最小值](https://codeforces.com/problemset/problem/911/A)

 ## 解决方案
 ## 问题理解

 我们得到一个整数数组。 数组中的所有值中，有一个最小值，并且问题保证这个最小值至少出现两次。 

我们的任务是找到该最小值的任意两次出现之间的最小距离。 位置之间的距离只是它们的指数之间的差异。 

例如，在数组中：```
[5, 2, 7, 2, 9]
```最小值是`2`，出现在指数中`1`和`3`。 他们的距离是`3 - 1 = 2`，所以答案是`2`。 

数组大小可以大到`100000`。 有了这个约束，比较每对位置的算法将需要大约`10^10`最坏情况下的操作，远远超出了2秒的时间限制。 我们需要一个能够在线性时间内处理数组的解决方案。 

一些边缘情况值得关注。 

考虑一个数组，其中每个元素都是最小值：```
4
1 1 1 1
```最小值出现在指数处`0, 1, 2, 3`。 最近的一对是相邻的，所以答案是`1`。 仅比较第一个和最后一个出现的粗心实现将错误地返回`3`。 

考虑最小值分布不均匀的情况：```
5
2 8 2 3 2
```最小值出现在指数处`0, 2, 4`。 距离是`2`和`2`，所以答案是`2`。 我们必须检查所有连续出现的事件，而不仅仅是一对。 

另一个重要的情况是最小有效输入：```
2
3 3
```最小值出现在两个位置，答案是`1`。 在这种边界情况下，指数计算中经常出现相差一的错误。 

## 方法

 一个简单的解决方案是首先找到所有出现的最小值，然后比较这些出现的每一对并取最小距离。 

这是有效的，因为答案被定义为包含最小值的两个位置之间的最小距离。 如果有`k`发生的情况，我们可以检查所有`k(k-1)/2`配对并计算它们的距离。 

当许多元素等于最小值时就会出现问题。 在最坏的情况下，所有`100000`元素是最小值。 那么我们需要：```
100000 × 99999 / 2 ≈ 5 × 10^9
```配对比较，这太慢了。 

关键的观察是，在我们知道最小值之后，只有它的位置才重要。 假设最小值出现在以下位置：```
p1 < p2 < p3 < ... < pk
```如果我们想要任意两次出现之间的最小距离，则它必须出现在该排序列表中的两个连续位置之间。 

为什么？ 如果我们采取立场`pi`和`pj`和`j > i + 1`，那么它们之间至少出现一次。 距离`pj - pi`大于该区间内的任一相邻间隙。 这样的一对永远无法产生最小距离。 

这意味着我们只需要检查最小值的连续出现。 

我们首先可以找到数组的最小元素。 然后我们再次扫描数组，记住最小值出现的最新位置。 每次我们发现另一个事件时，我们都会计算到前一个事件的距离并更新答案。 

这给出了线性时间解。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取数组。 
2. 找出数组中的最小值。 
3. 初始化`last = -1`表示尚未出现最小值。 
4. 初始化`answer`具有非常大的价值。 
5. 从左到右扫描阵列。 
6. 每当当前元素等于最小值时：

 1.如果`last`已经存储了先前出现的情况，计算距离`current_index - last`。 
2. 更新`answer`如果这个距离更小。 
3. 将当前索引存储在`last`。 
7. 扫描完成后，打印`answer`。 

这样做的原因是扫描自然会遇到按递增索引顺序出现的最少次数。 每个计算出的距离恰好是连续两次出现最小值之间的间隙。 

### 为什么它有效

 设最小值的位置为：```
p1 < p2 < p3 < ... < pk
```该算法计算所有距离：```
p2 - p1
p3 - p2
...
pk - p(k-1)
```考虑任何不连续的对`pi`和`pj`和`j > i + 1`。 其距离为：```
pj - pi
```在这个区间内至少有一个连续的间隙。 该连续间隙小于或等于`pj - pi`。 因此，两次出现之间的最小可能距离必须出现在连续出现中。 

由于该算法仅检查每个连续对一次并取这些距离的最小值，因此它总是返回正确的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    mn = min(a)

    last = -1
    ans = n

    for i in range(n):
        if a[i] == mn:
            if last != -1:
                ans = min(ans, i - last)
            last = i

    print(ans)

if __name__ == "__main__":
    solve()
```第一步是找到数组的最小值。 只有出现该值才能得出答案，因此之后可以忽略所有其他元素。 

变量`last`存储最小值出现的最新索引。 当发现另一个事件时，两个索引之间的距离恰好是连续最小值之间的差距。 

变量`ans`追踪迄今为止看到的最小差距。 它被初始化为`n`，它比任何有效答案都安全地大，因为长度数组中两个索引之间的最大距离`n`是`n - 1`。 

一个常见的错误是更新`last`在计算距离之前。 这样做会将索引与其自身进行比较，并且总是产生零。 正确的顺序是先计算间隙，然后更新`last`。 

不存在溢出问题，因为索引差异最多是`99999`，完全在 Python 的整数范围内。

 ## 边缘情况

 ### 所有元素都相等

 输入：```
4
1 1 1 1
```最小值为`1`，出现在指数中`0, 1, 2, 3`。 

该算法计算距离：```
1 - 0 = 1
2 - 1 = 1
3 - 2 = 1
```这些值的最小值是`1`，这是正确答案。 仅查看第一个和最后一个出现的位置会错误地生成`3`。 

### 间距不均匀的最小值

 输入：```
5
2 8 2 3 2
```最小值为`2`，出现在指数中`0, 2, 4`。 

该算法计算：```
2 - 0 = 2
4 - 2 = 2
```答案就变成了`2`。 

这说明了为什么检查连续出现的情况就足够了。 不连续的对`(0, 4)`有距离`4`，它更大并且不是最优的。 

### 最小有效输入

 输入：```
2
3 3
```最小值出现在索引处`0`和`1`。 

第一次出现的集合`last = 0`。 第二次出现产生：```
1 - 0 = 1
```算法输出`1`，这是二元数组中唯一可能的距离。 此案例证实初始化和边界处理是正确的。
