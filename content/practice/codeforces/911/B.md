 ## 解决方案
 ## 问题理解

 我们得到了两块不可分割的蛋糕块，其中一块蛋糕被分成了几块`a`碎片和另一个分裂成`b`件。 我们还有`n`盘子，我们必须将所有碎片分配到这些盘子上。 

每个盘子必须至少收到一块蛋糕，并且不允许任何盘子将两个蛋糕的碎片混合在一起。 因此，每个盘子都完全分配给一个蛋糕，然后填充该蛋糕的一定数量的碎片。 

我们的目标不仅仅是找到任何有效的分布，而是最大化放置在任何盘子上的最小数量的棋子。 换句话说，如果我们查看每个板上最终有多少件，我们希望最大化所有板上的最小负载。 

关键的结构是我们正在分区`a`和`b`分成一定数量的组，每组对应一个盘子，并且每组必须至少包含`x`件。 我们想要最大可能的这样`x`。 

限制很小：`a, b ≤ 100`,`n ≤ 200`。 这立即排除了任何繁重的组合搜索。 即使 O(n²) 或 O(n³) 解决方案也可以，但该结构建议对每个候选值进行直接算术可行性检查。 

当一个蛋糕可以满足大多数盘子的需求时，就会出现一种微妙的边缘情况，但将其分成太多组会迫使小组规模变小。 例如，如果`a = 100`,`b = 1`， 和`n = 50`，一种幼稚的方法可能会尝试均匀分配每个蛋糕，而不考虑每个盘子必须完全分配给一个蛋糕。 

另一个棘手的情况是当`n`接近于`a + b`。 由于每个盘子至少需要一块，所以我们被迫放入许多单块盘子，这强烈限制了答案很小，即使一个蛋糕很大。 

## 方法

 思考这个问题的一种暴力方式是尝试所有可能的方法将两个蛋糕分成几组。 对于每个蛋糕，我们选择它占据的盘子数量，例如`i`第一个蛋糕的盘子和`n - i`第二个盘子。 然后我们检查是否可以拆分`a`进入`i`零件和`b`进入`n - i`零件，使得每个零件的尺寸至少`x`。 

对于固定的`x`，这个可行性检查很简单：蛋糕`a`最多可以支持`a // x`盘子和蛋糕`b`最多可以支持`b // x`盘子。 所以我们只需要检查是否存在分裂`n`化为两个非负整数`i`和`n - i`这样：`i ≤ a // x`和`n - i ≤ b // x`。 

对所有可能的分裂进行暴力破解`i`每个值都是 O(n)`x`，如果我们也尝试所有`x`值达到 max(a, b)，我们得到 O(n * max(a, b))，这已经很小但没有必要。 

关键的观察是对于固定的`x`，我们不需要尝试所有的分割。 我们只需要知道我们能形成的板片总数是否至少为`n`。 蛋糕1可以贡献`a // x`盘子、蛋糕2个可以贡献`b // x`板，所以总数是`(a // x) + (b // x)`。 

因此可行性简化为一个简单的条件，我们可以对`x`因为如果一个值`x`有效，任何较小的值也有效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解| O(n * 最大(a,b)) | O(1) | O(1) | 太慢/不必要|
 | 二分查找+可行性检查| O(log(最大(a,b))) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们想要找到最大的整数`x`使得两个蛋糕至少可以被分割成`n`板总数，每个板至少接收`x`件。 

1. 定义一个函数`can(x)`检查我们是否至少可以形成`n`板，如果每个板必须至少包含`x`件。 

我们计算每个蛋糕可以容纳多少个盘子：`a // x`从第一个蛋糕开始`b // x`从第二块蛋糕开始。 

板的总数是它们的总和，我们将其与`n`。 
2. 设置二分查找范围`x`从`1`到`max(a, b)`。 

上限之所以有效，是因为没有一个盘子可以容纳比最大的蛋糕本身更多的块。 
3. 执行二分查找。 对于每个中点`mid`， 评价`can(mid)`。 

如果可能的话，我们尝试更大的值，因为我们想要最大化`x`。 否则，我们会减少搜索空间。 
4.最终答案是最大的`x`为此`can(x)`返回真。 

步骤 3 背后的关键思想是单调性：一旦某个特定的板尺寸变得不可能，所有更大的尺寸也是不可能的。 

### 为什么它有效

 对于任何固定的`x`，将蛋糕分成至少大小的盘子`x`相当于贪婪地将其切成大小块`x`，剩余的被丢弃或合并到早期的盘子中。 这些块的数量正好是`a // x`。 这给出了一个严格的上限：没有任何安排可以产生超过`a // x`蛋糕的有效盘子`a`。 这同样适用于`b`。 

因此，可行性仅取决于最大可能板数之和是否满足`n`。 由于该计数减少为`x`增加，搜索空间是单调的，这保证了二分搜索的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(x, n, a, b):
    return (a // x) + (b // x) >= n

n, a, b = map(int, input().split())

lo, hi = 1, max(a, b)
ans = 1

while lo <= hi:
    mid = (lo + hi) // 2
    if can(mid, n, a, b):
        ans = mid
        lo = mid + 1
    else:
        hi = mid - 1

print(ans)
```这`can`函数对之前导出的可行性条件进行编码。 每个蛋糕独立贡献的盘子数量等于多少个整组的大小`x`它可以分为。 二分查找探索所有可能的值`x`高效。 

搜索范围从 1 开始，因为每个盘子必须至少包含一件，并且最多可达`max(a, b)`因为没有一个盘子可以超过最大的单个蛋糕的尺寸。

 ## 边缘情况

 一种边缘情况是当`n`等于`a + b`。 例如：```
n = 5, a = 3, b = 2
```这里每个盘子必须恰好包含一件。 该算法评估`x = 1`:`3 // 1 + 2 // 1 = 5`，匹配`n`，所以答案是 1. 任意`x ≥ 2`立即失败，因为每个蛋糕甚至无法形成足够的盘子。 

另一种边缘情况是一个蛋糕比另一个大得多，例如：```
n = 4, a = 100, b = 1
```为了`x = 25`，我们得到`100 // 25 + 1 // 25 = 4 + 0 = 4`，有效。 为了`x = 26`，我们得到`3 + 0 = 3`，失败了。 该算法正确地捕捉到了小蛋糕除了`x = 1`，而大蛋糕本身就必须满足其余的要求。
