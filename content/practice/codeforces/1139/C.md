 ## 解决方案
 ## 问题理解

 我们有一棵树，其边缘的颜色要么是红色（`0`）或黑色（`1`）。 我们必须计算有多少个长度的序列`k`由树顶点组成的都是“好”的。 

对于一个序列`[a₁, a₂, ..., aₖ]`，我们反复沿着树中唯一的最短路径旅行`a₁`到`a₂`，然后从`a₂`到`a₃`， 等等。 如果在整个旅程中至少有一个黑边经过某处，则该序列被认为是好的。 

这棵树最多有`10^5`顶点，同时`k`至多是`100`。 可能的序列总数为`n^k`，这是一个天文数字。 甚至迭代所有序列也是不可能的。 由于树本身包含`10^5`顶点之间的路径，任何重复计算顶点之间路径的解决方案也会失败。 我们需要一些接近线性的东西`n`。 

关键的困难在于，良好性是由序列引起的路径集合上至少存在一个黑色边缘来定义的。 直接检查每个序列是没有希望的，所以我们需要间接地计算它们。 

当每个边缘都是黑色时，就会出现微妙的边缘情况。```
4 2
1 2 1
2 3 1
3 4 1
```唯一不好的序列是`[1,1]`,`[2,2]`,`[3,3]`， 和`[4,4]`。 不同顶点之间的任何移动都至少使用一条黑边。 仅查看黑色边缘的连接组件的解决方案将完全忽略该结构。 

另一个重要的情况是每个边缘都是红色的。```
4 3
1 2 0
2 3 0
3 4 0
```没有路径包含黑边，所以答案是`0`。 对接触多个顶点的序列进行计数的粗心实现会错误地报告肯定答案。 

一个更微妙的例子是：```
5 2
1 2 0
2 3 0
3 4 1
4 5 0
```顶点`{1,2,3}`form a red-only connected component. 序列如`[1,3]`不好，因为它们的路径完全位于红色边缘内。 对于`[5,5]`。 答案取决于纯红色组件的大小，而不取决于单个顶点。 

## 方法

 蛮力的想法很简单。 生成每个长度的序列`k`，模拟行走，判断是否至少有一条走过的边是黑色的。 

有`n^k`序列。 和`n = 10^5`和`k = 100`，这个数字超出了任何可以想象的计算范围。 即使对于很小的值，重复计算树中的路径也已经很昂贵了。 蛮力方法是正确的，因为它直接应用定义，但它立即变得无法使用。 

为了更快地找到东西，思考相反的问题会有所帮助。 

不要计算好的序列，而要计算**不好**的序列。 

当每条遍历的路径完全由红色边缘组成时，序列并不好。 

考虑从树中删除所有黑边。 剩下的图是仅由红色边形成的连通分量的集合。 

假设序列中的所有顶点都属于同一个红色分量。 然后，连续顶点之间的每条最短路径都完全位于该组件内部，因此每条遍历的边都是红色的。 顺序不好。 

假设序列包含来自两个不同红色分量的顶点。 这些组件之间的任何路径必须至少穿过一条已移除的边缘，这意味着至少有一条黑色边缘。 那么顺序就好了。 

这完全描述了不良序列的特征：

 当且仅当一个序列的所有顶点都属于由红边形成的图的同一连通分量时，该序列是坏的。 

如果红色分量有尺寸`s`，那么它贡献了`s^k`糟糕的序列，因为序列中的每个位置都可以独立地从该组件中选择任何顶点。 

序列总数为`n^k`。 

因此：`answer = n^k - Σ s^k`其中所有红色连通分量的总和。 

忽略黑边后，使用 DFS、BFS 或 DSU 可以轻松找到这些组件尺寸。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^k · n) 或更糟 | O(n) | 太慢了 |
 | 最佳 | O(n + log k · 分量数) | O(n) | 已接受 |

 ## 算法演练

 1. 仅使用红边构建图表（`x = 0`）。 

黑色边缘被忽略，因为它们分隔了确定不良序列的纯红色区域。 
2. 使用 DFS 或 BFS 查找此纯红色图的所有连通分量。 

每个组件代表不使用任何黑边连接的最大顶点集。 
3. 计算`total = n^k mod M`， 在哪里`M = 10^9 + 7`。 

这是所有可能序列的数量。 
4. 对于每个尺寸的红色分量`s`, 计算`s^k mod M`并从中减去它`total`。 

每个顶点都位于该组件内的序列都是不好的。 
5. 执行所有求模运算`10^9 + 7`。 
6.输出最终结果。 

### 为什么它有效

 去除黑色边缘后，顶点分裂成红色连通分量。 

如果序列的每个顶点都属于同一组件，则连续顶点之间的每条路径都完全保留在该组件内，并且仅使用红色边。 这样的顺序是不好的。 

如果序列包含来自不同组件的顶点，则连续选定顶点之间的某些路径必须穿过黑色边缘，因为不同的红色组件在没有黑色边缘的情况下会断开连接。 这样的顺序是好的。 

坏序列按其所有顶点所在的组件进行划分。 尺寸的组成部分`s`准确贡献`s^k`糟糕的序列。 对所有组件求和会将每个错误序列精确计数一次。 

从序列总数中减去坏序列的数量就剩下好序列的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def main():
    n, k = map(int, input().split())

    g = [[] for _ in range(n)]

    for _ in range(n - 1):
        u, v, x = map(int, input().split())
        u -= 1
        v -= 1

        if x == 0:
            g[u].append(v)
            g[v].append(u)

    visited = [False] * n

    ans = pow(n, k, MOD)

    for start in range(n):
        if visited[start]:
            continue

        stack = [start]
        visited[start] = True
        size = 0

        while stack:
            v = stack.pop()
            size += 1

            for to in g[v]:
                if not visited[to]:
                    visited[to] = True
                    stack.append(to)

        ans = (ans - pow(size, k, MOD)) % MOD

    print(ans)

if __name__ == "__main__":
    main()
```该图仅存储红色边缘。 这是该解决方案的核心观察结果。 我们对遍历黑色边缘不感兴趣，因为它们只是分隔生成不良序列的区域。 

DFS 计算每个红色连通分量的大小。 由于原始图是一棵树，因此纯红色图最多包含`n - 1`边缘，因此遍历它仍然是线性的。 

变量`ans`开始为`n^k`，所有序列的计数。 每个组件都贡献`size^k`坏序列，立即被减去。 

使用Python的内置`pow(base, exp, mod)`很重要。 价值观`n^k`和`size^k`没有模幂的话是巨大的。 

减法以模进行`MOD`。 写作```
(ans - value) % MOD
```避免负中间值。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + c log k) | O(n + c log k) | DFS 访问每个顶点一次，每个组件贡献一次模幂 |
 | 空间| O(n) | 邻接表、访问数组、DFS 堆栈 |

 这里`c`是红色连通分量的个数，最多为`n`。 自从`k ≤ 100`，模幂实际上是常数时间。 该算法与树的大小呈线性关系，并且很容易符合以下限制：`n = 10^5`。

 ## 边缘情况

 考虑一棵完全由黑色边缘组成的树。```
4 2
1 2 1
2 3 1
3 4 1
```删除黑色边缘留下四个孤立的顶点。 元件尺寸为`1,1,1,1`。 

该算法计算：```
4² - 1² - 1² - 1² - 1²
= 16 - 4
= 12
```唯一不好的序列是`[1,1]`,`[2,2]`,`[3,3]`， 和`[4,4]`。 每隔一个序列都至少穿过一个黑色边缘。 

现在考虑一棵完全由红色边缘组成的树。```
4 2
1 2 0
2 3 0
3 4 0
```删除黑边不会改变任何事情。 尺寸只有一个组成部分`4`。 

该算法计算：```
4² - 4² = 0
```每条路径都是红色的，所以没有顺序是好的。 

最后，考虑混合颜色。```
5 2
1 2 0
2 3 0
3 4 1
4 5 0
```红色组件有尺寸`3`和`2`。 

该算法计算：```
5² - 3² - 2²
= 25 - 9 - 4
= 12
```坏序列正是那些两个顶点都属于的序列`{1,2,3}`或者两者都属于`{4,5}`。 连接两个组件的任何序列都必须穿过黑边`(3,4)`，让它变得很好。 这正是解决方案所重视的属性。
