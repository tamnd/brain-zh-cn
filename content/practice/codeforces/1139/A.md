 ## 解决方案
 ## 问题理解

 我们得到一串从 1 到 9 的数字。我们的任务是计算有多少个子串（由任何连续的索引范围定义）代表偶数。 如果子字符串的最后一位数字是偶数，则该子字符串是偶数，因为数字的奇偶校验完全由最后一位数字决定。 

输入大小最多可达 65,000 位。 这排除了任何显式构造所有子字符串的解决方案，因为子字符串的总数大致为$n(n+1)/2$，超过 20 亿$n = 65,000$。 任何尝试迭代所有子字符串并将它们转换为整数的算法都会太慢。 

一个微妙的边缘情况是完全由奇数数字组成的字符串。 例如，“1357”应该产生 0 的输出，因为没有子字符串以偶数结尾。 另一个边缘情况是当每个数字都是偶数时，例如“246”，每个子字符串都会被计算在内。 正确处理这些取决于根据最后一位数字对子字符串进行计数，而不是尝试对完整子字符串进行算术运算。 

## 方法

 暴力方法会迭代子字符串的所有可能的起始和结束索引，将子字符串转换为数字，并检查它是否能被 2 整除。这是正确的，但太慢了，因为它需要$O(n^2)$子字符串提取和整数转换。 和$n = 65,000$，这大约是$2 \times 10^9$操作，这超出了 0 秒时间约束的合理限制。 

关键的见解是数字的奇偶性仅取决于其最后一位数字。 以位置结尾的子字符串$i$是即使$s[i]$是 2、4、6 或 8 之一。在此位置结束的每个子串都可以直接计数：正好有$i$以索引结尾的子字符串$i$。 因此，我们不生成子字符串，而是简单地迭代字符串，每当看到偶数位时，我们将其位置（1 索引）添加到运行总计中。 这将时间复杂度降低到$O(n)$并避免不必要的字符串或整数操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取输入字符串及其长度。 我们将使用从 1 开始的索引从左到右迭代字符串。 
2. 将计数器初始化为零。 该计数器将累积偶数子串的总数。 
3. 对于索引处的每个字符$i$，将其转换为整数以检查其奇偶性。 
4. 如果数字是偶数 (2, 4, 6, 8)，则将计数器增加$i$。 这是有效的，因为在此位置结束的每个子字符串都由其从 1 到 的起始索引唯一标识$i$。 
5. 继续直到字符串末尾，然后打印计数器。 

为什么它有效：不变的是每个索引$i$, 结尾的子串总数$i$正是$i$，每个以偶数结尾的子串都对答案有贡献。 由于我们只访问每个索引一次并计算所有以偶数数字结尾的子字符串，因此不会遗漏或重复计算有效的子字符串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
s = input().strip()

count = 0
for i, c in enumerate(s, start=1):
    if int(c) % 2 == 0:
        count += i

print(count)
```该解决方案读取输入字符串并使用从 1 开始的索引对其进行枚举。 对于每个字符，我们检查它是否为偶数，如果是，则将其索引添加到总计数中。 我们不需要存储子字符串或将多个字符转换为数字，这可以降低内存和计算量。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    s = input().strip()
    count = 0
    for i, c in enumerate(s, start=1):
        if int(c) % 2 == 0:
            count += i
    return str(count)

 ## 边缘情况

 对于单位数字字符串“1”，算法正确输出 0，因为唯一的子字符串以奇数数字结尾。 对于像“22222”这样的全偶数位的字符串，每个索引将其从 1 开始的位置贡献给总数，得到 1+2+3+4+5 = 15。对于像“135792”这样的交替奇偶校验，唯一的偶数位在位置 2 和 6，对总数贡献 2+6=8，确认算法不会遗漏或重复计算子字符串。
