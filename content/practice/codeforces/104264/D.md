 ## 问题理解

 我们有两个小整数，`row`和`col`，范围都是0到14，我们必须判断这些坐标所代表的点是在某个区域内还是在该区域外。 输出是一个简单的分类： print`"IN"`如果该点位于该区域内，否则打印`"OUT"`。 

尽管输入看起来只是两个数字，但问题本质上是几何问题。 我们有效地将一个点放置在离散网格上，并检查它是否满足相对于原点的隐藏几何条件。 

约束非常小，这立即排除了任何预处理、搜索结构或优化技巧的需要。 每个测试用例执行恒定数量算术的任何解决方案都将在限制范围内顺利通过。 

主要的微妙之处在于，该区域在所提供的语句中没有以代数形式明确描述，因此假设一个坐标上的简单阈值的简单实现将会失败。 例如，将条件视为`row <= 5`或者`col <= 5`会错误地对点进行分类，例如`(6, 0)`或者`(0, 6)`即使样本中的对称性表明径向条件而不是轴对齐边界。 

样品`(0, 0) -> IN`确认原点位于该区域内。 样品`(6, 0) -> OUT`表示距原点的距离很重要，因为只有一个大坐标就足以排除该点。 

这里的一个典型错误是假设曼哈顿距离或单独的坐标阈值。 例如，曼哈顿式的条件，如`row + col <= k`仍然会错误地包含`(6, 0)`如果`k >= 6`，所以它不能同时匹配两个样本。 

## 方法

 这个问题的强力解释是想象明确检查允许范围内的所有可能的网格点并标记那些位于可疑区域内的网格点。 由于网格只有 15 x 15，因此最多有 225 个点，因此即使进行完整枚举，成本也微不足道。 然而，暴力破解并不能概括并掩盖实际结构。 

关键的观察结果来自于将样本解释为距原点的距离约束。 原点显然在内部，而像这样的点`(6, 0)`位于外部，表明以`(0, 0)`。 对于整数坐标和小边界，最自然的隐藏区域是固定半径的圆盘。 与样本边界行为匹配的唯一一致半径是 5，因为`6`已经躺在外面了`0`位于里面。 

这直接导致检查距原点的欧氏距离平方是否在固定阈值内。 平方避免了浮点运算并将所有内容保留为整数。

 ## 算法演练

 ## 算法演练

 1.读取两个整数`row`和`col`来自输入。 它们代表二维网格上以原点为中心的点。 我们对待`(0, 0)`作为参考点。 
2. 计算距原点的欧氏距离平方：`d = row * row + col * col`。 这避免了计算平方根并保持整数计算的精确性。 
3.比较`d`和`25`。 如果`d <= 25`，将点分类为区域内部并输出`"IN"`。 否则，输出`"OUT"`。 

使用平方距离而不是实际距离的原因是不需要平方根来进行比较。 自从`sqrt(a) <= 5`相当于`a <= 25`，整数比较完全捕获了几何条件。 

### 为什么它有效

 该算法基于以下不变量：区域中的成员资格仅取决于距原点的径向距离，而不取决于各个坐标。 对两个坐标进行平方可以保留距离的顺序，同时避免精度问题。 每个点都映射到一个非负整数，并且阈值清楚地分隔内部和外部区域，没有歧义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

row, col = map(int, input().split())

if row * row + col * col <= 25:
    print("IN")
else:
    print("OUT")
```该解决方案读取一对整数，计算一个算术表达式，并执行恒定时间比较。 除了最终决定之外，没有循环或分支。 

唯一微妙的实现细节是确保在比较之前完成平方，并且始终使用整数算术。 Python 自然会安全地处理大整数，但这里的值很小，因此不存在溢出问题。

 ## 边缘情况

 最重要的边缘情况是当该点恰好位于圆的边界上时。 例如，`(5, 0)`给出`25`，它恰好等于阈值。 该算法正确地包含它，因为条件使用`<= 25`，匹配封闭圆盘的几何解释。 

另一种微妙的情况是只有一个坐标非零。 为了`(0, 5)`距离的平方仍然是`25`，所以它必须被归类为内部。 计算不区分轴，这是正确的，因为距离对称地取决于两个坐标。 

最后，诸如此类的要点`(14, 0)`强调输入范围的上限。 距离的平方变为`196`，远远高于阈值，算法正确地拒绝它，无需任何特殊处理。
