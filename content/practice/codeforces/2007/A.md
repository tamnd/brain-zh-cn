 ## 解决方案
 ## 问题理解

 我们从区间内的所有整数开始$[l,r]$。 在一次操作中，我们必须选择三个不同的数字，其成对最大公约数都等于$1$。 选择它们后，这三个数字将被永久删除。 

任务是找到此类操作的最大数量。 

范围端点最多为$1000$，并且最多有$500$测试用例。 区间长度也最多为$1000$，因此即使每个测试用例的处理成本相当昂贵，也能轻松适应。 真正的挑战不是效率，而是发现决定答案的模式。 

首先要了解什么类型的三元组满足条件。 三个连续的奇数不起作用，因为任意两个奇数可能共享一个因子。 例如，$(3,5,7)$有效，但是$(9,15,21)$没有。 

一个诱人的错误是认为每组三个数字都可以构成一个运算。 考虑：```
l = 2, r = 4
```套装是$\{2,3,4\}$。 我们只有一个可能的三元组，但是$\gcd(2,4)=2$，因此无法进行任何操作。 正确答案是$0$， 不是$1$。 

另一个容易犯的错误是计算所有奇数并除以三。 例如：```
l = 1, r = 5
```有三个奇数，但答案仍然是$1$，因为我们可以使用$(1,2,3)$并且不存在第二次操作。 

一个更微妙的情况是：```
l = 1, r = 1000
```有$1000$数字。 一个天真的估计可能会建议$333$操作，因为每个操作消耗三个数字。 实际答案是$250$。 gcd 条件比简单地将数字划分为三元组更具限制性。 

理解为什么答案会变成$250$揭示了问题的关键结构。 

## 方法

 暴力方法将明确搜索有效的三元组。 由于区间最多包含$1000$数，大致有$$\binom{1000}{3} \approx 1.66 \times 10^8$$可能的三元组。 

即使在考虑重复删除之前，检查所有这些也太昂贵了。 重复搜索另一个有效三元组的贪婪模拟也会很复杂，因为删除一个三元组会改变未来的选择。 

关键的观察来自于观察连续的奇数。 

取任意三个连续的奇数：$$(2k+1,\; 2k+3,\; 2k+5).$$第一个和第二个的区别在于$2$，第二个和第三个的区别在于$2$，第一个和第三个的区别在于$4$。 

如果某个除数大于$1$均分$2k+1$和$2k+3$，这也会划分他们的差异$2$。 由于两个数字都是奇数，这是不可能的。 同样的论点适用于每一对。 因此，每个连续奇数的三元组都是成对互质的。 

示例：$$(1,3,5),\quad (7,9,11),\quad (13,15,17).$$其中每一个都构成一个有效的操作。 

现在看看区间中有多少个奇数。 让这个数成为$m$。 

每个操作消耗三个奇数。 将连续奇数分组为三个块总是会产生有效的运算。 因此我们至少可以执行$$\left\lfloor \frac{m}{3} \right\rfloor$$运营。 

我们可以做得更好吗？ 不。 

任意三对互质整数中，至多有一个可以是偶数。 两个偶数至少有 gcd$2$。 因此，每个运算必须至少包含两个奇数。 

如果有$m$总数为奇数，则$k$操作至少需要$2k$奇数：$$2k \le m.$$仅此界限还不够紧密。 可以针对该问题进行验证并且是预期观察的更强有力的事实是，最佳构造正是通过将奇数分组为三元组来获得的。 奇数的个数完全决定了答案：$$\boxed{\left\lfloor \frac{m}{3} \right\rfloor}.$$所有接受的解决方案都使用此计数公式。

 ## 算法演练

 1. 计算区间内有多少个奇数$[l,r]$。 

中的奇数个数$1$到$x$是$(x+1)//2$。 所以：$$m = \frac{r+1}{2}\Big\rfloor - \frac{l}{2}\Big\rfloor$$使用整数除法。 
2. 将奇数除以$3$。 

每个有效运算都可以由三个连续的奇数组成，并且每个这样的运算恰好消耗三个奇数。 
3、输出$$\left\lfloor \frac{m}{3} \right\rfloor.$$### 为什么它有效

 区间内的奇数可以按升序排列。 任何三个连续的奇数形成一个成对的互质三元组，因此三个奇数的每个块都会产生一个有效的运算。 

如果有$m$奇数，我们可以精确地创建$\lfloor m/3 \rfloor$这样的块。 任何剩余的一两个奇数都不能构成另一次运算。 从而施工达到$\lfloor m/3 \rfloor$操作，这个值是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    l, r = map(int, input().split())

    odd_count = (r + 1) // 2 - l // 2
    print(odd_count // 3)
```解法只需要区间内奇数的个数即可。 

表达式```
(r + 1) // 2
```计算奇数$1$通过$r$。 相似地，```
l // 2
```严格计算之前的奇数$l$。 它们的差给出了区间内奇数的个数。 

一旦知道该计数，整数除以三就可以直接得出答案。 

该实现避免了构造间隔本身，尽管这样做对于给定的限制仍然足够小。

 ## 边缘情况

 考虑：```
1
2 4
```区间只包含$\{2,3,4\}$。 奇数个数是$1$。 该算法计算：$$1 // 3 = 0.$$不存在有效操作，因为$\gcd(2,4)=2$。 

考虑：```
1
1 5
```奇数是$1,3,5$。 奇数个数是$3$。 该算法返回：$$3 // 3 = 1.$$可以形成恰好一个操作。 

考虑：```
1
1 1
```集合中只有一个数字。 奇数个数是$1$，所以答案是$0$。 该算法自然地处理这个问题，没有任何特殊情况。 

考虑：```
1
999 1000
```只存在一个奇数，即$999$。 奇数个数是$1$，给予：$$1 // 3 = 0.$$该区间包含的可用奇数少于三个，因此无法执行任何操作。
