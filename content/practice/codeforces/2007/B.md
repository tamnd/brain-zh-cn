 ## 解决方案
 ## 问题理解

 我们得到一个数组，但操作并不直接修改位置。 相反，每个操作都以值为目标：每当我们看到一个范围时$[l, r]$，当前值位于该数字区间内的每个元素都恰好递增或递减 1。 

在每次这样的全局转换之后，我们都会被要求提供数组中当前存在的最大值。 

所以结构不是“更新索引”，而是“根据当前值更新所有元素”。 这使得数组的行为就像一个整数的多重集，以小块的形式连续向左或向右移动。 

关键的困难在于值会随着时间的推移而变化，因此属于给定区间的元素集$[l, r]$每次操作后都会发生变化。 每次操作扫描所有元素的简单模拟太慢，因为$n$和$m$上升到$10^5$，这会导致$O(nm)$最坏情况下的行为。 

一个微妙的边缘情况是所有元素始终位于每个查询的活动范围内。 在这种情况下，每次操作都会移动整个阵列，任何重复重新扫描或重建结构的解决方案都会成倍降低性能。 

另一种边缘情况是只有一个值重复受到影响。 即使这样，该值也可以“行走”穿过数轴，并且依赖于固定索引或静态存储桶的简单结构将失去对它的跟踪。 

## 方法

 暴力破解的想法很简单：对于每个操作，迭代整个数组并将更新应用于满足值条件的元素。 这是正确的，因为它直接遵循定义，但它的成本$O(n)$每次操作，导致$O(nm)$，太大了。 

为了改进这一点，我们不再将结构视为数组，而是将其视为值的频率图。 每个操作仅与连续范围的值交互，因此核心任务变成重复提取键的切片，并按$\pm 1$，并将它们合并回来。 

关键的观察是值总是聚集的：只有键在$[l, r]$移动，并且它们均匀地移动。 因此，我们不是处理单个元素，而是一次处理整组相同的值。 这将问题转化为动态有序结构中的重复范围提取和重新插入。 

主要挑战是按排序顺序维护这些组，同时支持对键的范围查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nm)$|$O(n)$| 太慢了|
 | 有序地图/分组模拟|$O((n+m)\log n)$摊销|$O(n)$| 已接受 |

 ## 算法演练

 我们维护一个不同值的排序列表和一个存储每个值出现次数的字典。 

每个操作都会更新此结构中的键范围。 

1. 维护当前不同值的排序列表。 

这让我们可以快速找到里面的值段$[l, r]$。 
2. 维护频率图`cnt[value]`每个值出现的次数。 

这避免了接触单个元素。 
3. 对于每个操作，使用二分查找找到排序值列表中最左边和最右边受影响的位置。 

这可以准确识别哪些值在更新范围内。 
4. 将所有受影响的值及其计数提取到临时列表中。 

我们通过删除它们的频率条目从逻辑上将它们从结构中删除。 
5. 根据操作，重新插入移动+1 或-1 的每个提取值。 

如果移位值已经存在，我们将合并计数。 
6. 确保当新值出现或旧值完全消失时更新排序列表。 

这保留了未来二分搜索的正确性。 
7. 处理完每个操作后，最大值就是排序列表的最后一个元素。 

重要的想法是，每个不同的值在整个过程中仅插入和删除有限次数，因此摊余成本保持可控。 

### 为什么它有效

 在每一步中，该结构都准确地表示数组中当前值的多重集。 每个操作仅移动值位于连续区间内的元素，并且这些元素移动固定偏移量±1，因此按值分组是无损的。 因为我们总是合并相等的值并保持排序顺序，所以表示在对数时间内保持精确且可查询。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from bisect import bisect_left, bisect_right

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    cnt = {}
    for x in a:
        cnt[x] = cnt.get(x, 0) + 1

    keys = sorted(cnt)

    def add_key(x):
        if x in cnt:
            return
        # insert into sorted list
        i = bisect_left(keys, x)
        keys.insert(i, x)

    def remove_key(x):
        i = bisect_left(keys, x)
        if i < len(keys) and keys[i] == x:
            keys.pop(i)

    for _ in range(m):
        op, l, r = input().split()
        l = int(l)
        r = int(r)

        # find affected range in keys
        L = bisect_left(keys, l)
        R = bisect_right(keys, r)

        affected = keys[L:R]
        if op == '+':
            delta = 1
        else:
            delta = -1

        # remove old keys
        for x in affected:
            cnt_x = cnt[x]
            del cnt[x]
            remove_key(x)

            nx = x + delta
            cnt[nx] = cnt.get(nx, 0) + cnt_x
            add_key(nx)

        if keys:
            sys.stdout.write(str(keys[-1]) + "\n")
        else:
            sys.stdout.write("0\n")

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```该实现保留了活动值的排序列表和频率字典。 每个操作都使用二分查找找到受影响的值区间，然后在一批中移动整组相等的值。 

微妙的部分是保持之间的一致性`cnt`和`keys`。 每当一个值完全消失时，它必须从两个结构中删除； 否则过时的密钥会破坏未来的二进制搜索。 

## 工作示例

 ### 示例 1

 输入：```
a = [1, 2, 3]
+ 1 2
- 2 3
```我们跟踪关键状态：

 | 步骤| 运营| 按键| 最大|
 | --- | --- | --- | --- |
 | 0 | 初始化| [1,2,3]| 3 |
 | 1 | +1..2 | [1,2,3] → [1,2,3] | 3 |
 | 2 | -2..3 | -2..3 [1,2,3] → [1,2,3] | 3 |

 这表明，即使值在内部发生变化，也始终可以从有序键结构中获得最大值。

 输入：```

```| 步骤| 运营| 按键| 最大|

 最大值保持稳定，因为只有下段受到影响。 

这些示例证实，即使在重复移位的情况下，按值分组也能保持正确性。

 ## 边缘情况

 关键的边缘情况是所有值都落入每个查询范围内。 在这种情况下，每次操作都会将整个多重集移动±1，并且正确性完全取决于正确合并频率而不是重复重建结构。 

另一种边缘情况是许多值在重复递减或递增后合并为单个值。 如果实现无法正确合并计数，则排序结构将包含重复项或过时的条目，从而破坏未来的范围查询并产生不正确的最大值。 

该算法自然地处理这两种情况，因为每个变换都应用于分组值的级别，并且排序的键列表始终与频率图同步。
