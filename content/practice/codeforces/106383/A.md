 ## 问题理解

 该任务询问阶乘的二进制表示形式末尾的零位数。 输入是单个整数`n`，输出是二进制值的多少倍`n!`在变成奇数之前可以除以 2。 的价值`n!`即使对于允许的最大输入，其本身也变得太大而无法直接构建。 

重要的转变是停止考虑阶乘的数字，而是考虑因子。 二进制中的尾随零意味着该数字的因子为`2`。 如果一个数可以被`2^k`但不是由`2^(k+1)`，其二进制表示完全以`k`零。 问题是要求`2`里面`n!`。 

输入限制达到`10^6`。 循环遍历直到`n`是完全合理的，但是构建阶乘是不可能的，因为`n!`增长速度比输入大小快得多。 任何存储或重复操作阶乘本身的方法都会耗尽时间或内存。 

棘手的情况主要是关于正确计算因素。 为了`n = 1`，阶乘是`1`，其二进制表示为`1`，所以答案为零。 从错误点开始计数的解决方案可能会错误地添加两倍。 

例如：```
Input:
1

Output:
0
```中没有偶数`1!`，因此没有尾随零位。 

另一个常见的错误是只计算二的倍数而忽略更高的幂。 例如：```
Input:
8

Output:
7
```偶数贡献二的因数如下：`2`贡献一，`4`贡献了两个，`6`贡献一份，并且`8`贡献三。 总计为`1 + 2 + 1 + 3 = 7`。 一个粗心的实现，只计算偶数会得到`4`反而。 

## 方法

 直接的方法是计算阶乘并重复将其除以二，同时保持偶数。 这在数学上是正确的，因为每次除法都会从二进制表示中删除一个尾随零。 问题在于阶乘的大小。 为了`n = 10^6`，阶乘有数百万位，因此构造它并除以它需要操作一个巨大的整数。 

更好的方法是计算乘法中出现了多少个二的因数`1 * 2 * 3 * ... * n`。 每个偶数至少贡献二的一个因数。 能被四整除的数字贡献一个额外的因素，能被八整除的数字贡献另一个因素，并且这种模式仍在继续。 

的倍数的个数`2`其中第一`n`整数是`floor(n / 2)`。 来自倍数的附加因素的数量`4`是`floor(n / 4)`。 来自倍数的附加因子的数量`8`是`floor(n / 8)`。 将这些值相加，直到 2 的幂大于`n`给出尾随二进制零的确切数量.

 暴力破解的想法失败了，因为它试图表示乘法的结果。 优化的想法只计算重要的质因数，因此它将问题从处理巨大的数字减少到执行较小的对数除法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n 的大小！× 划分数) | O(n 的大小！) | 太慢了|
 | 最佳| O(log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`n`并将答案初始化为零。 答案将存储其中包含的两个因子的总数`n!`。 
2. 从价值开始`2`并反复乘以`2`。 对于每一个二的幂`p`， 添加`n // p`到答案。 
3.当两者的当前功率大于时停止`n`。 没有号码来自`1`到`n`可以包含那么多的二的因子，所以更大的幂没有任何贡献。 
4. 打印累计答案。 

这样做的原因是，每次出现因数为 2 的数字时`1`到`n`在二进制中创建一个尾随零。 计算倍数`2`找到第一个因子，计算`4`找到这些数字包含的额外因素，并继续使用更高的幂来捕获所有可能的贡献。 

为什么它有效：

 素数的指数`p`阶乘中的数是通过添加的倍数给出的`p`，那么的倍数`p²`，那么的倍数`p³`， 等等。 这里的质数是`2`，所以总和正好是：`floor(n/2) + floor(n/4) + floor(n/8) + ...`这个值是最大的`k`这样`2^k`划分`n!`。 由于二进制尾随零恰好对应于二的一个因数，因此该值是所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    ans = 0
    power = 2

    while power <= n:
        ans += n // power
        power *= 2

    print(ans)

if __name__ == "__main__":
    solve()
```变量`ans`存储迄今为止找到的两个因子的总数。 循环开始于`2`因为计算的每个因子都必须来自二的倍数。 

乘法`power *= 2`按顺序移动`2, 4, 8, 16, ...`。 每次迭代都会计算有多少个数字包含这个 2 的幂作为除数。 整数除法给出了精确的倍数。 

Python 整数不会溢出，因此答案不需要特殊处理。 最大可能的答案比阶乘本身小得多，并且循环只运行大约二十次`n = 10^6`。

 ## 边缘情况

 对于输入：```
1
```循环永远不会运行，因为`2 > 1`。 答案仍然为零，这与以下事实相符`1! = 1`没有尾随零位。 

对于输入：```
8
```算法访问幂`2`,`4`， 和`8`。 它添加了`8 // 2 = 4`,`8 // 4 = 2`， 和`8 // 8 = 1`，生产`7`。 这可以处理以下数字的情况`8`贡献二的倍数，并防止只计算偶数的常见错误。 

对于输入：```
1000000
```该算法从不尝试构建`1000000!`。 它只检查最多两个的幂`524288`，添加每个贡献。 最终的答案是`999993`，这完全来自因子计数而不是因子构造。
