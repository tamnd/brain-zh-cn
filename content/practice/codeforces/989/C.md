 ## 解决方案
 ## 问题理解

 我们被要求构建一个矩形网格并用四个字母填充它，每个字母代表一种花。 网格的设计应使得当我们单独查看每个字母时，使用边缘邻接来计算连接的组件，四个字母的组件数量与给定的目标相匹配$a, b, c, d$。 

这里的连接组件是指同一字母的最大单元格集合，您可以使用上、下、左、右步骤在单元格之间移动，而无需离开该字母。 

关键的自由度是我们没有给出网格大小。 我们可以任意选择$n, m \le 50$，然后相应地设计网格。 

约束足够小，我们不必担心计算复杂性，但它们强烈暗示解决方案是建设性的，而不是基于搜索的。 随机生成网格和测试组件计数的强力尝试是不可靠的，因为连接是全局的，并且小的局部更改可能会不可预测地合并或拆分组件。 

一个天真的想法是尝试放置$a$单独的 A 区，$b$单独的 B 区域，依此类推，每个区域作为一个小块。 最直接的失败情况是，如果同一字母的两个块即使在角落或边缘接触，它们也会合并为一个组件，从而错误地减少计数。 例如，将两个单个 A 单元放置在$(1,1)$和$(1,2)$立即将两个组件折叠成一个。 

因此，核心困难不是放置单元格，而是保证每个字母的出现都是一个孤立的组件。 

## 方法

 蛮力思维方式是将其视为放置问题：尝试放置$a+b+c+d$网格上标记的单元格并回溯以确保没有两个相同的字母相邻。 这很快就会变成组合性的，因为每个布局决策都会以非本地方式限制未来的布局。 即使在一个$50 \times 50$在网格中，朴素的回溯将探索指数数量的部分配置。 

关键的观察是，我们可以通过设计网格来完全消除连通性问题，使同一字母的两个单元格不会相邻。 如果这一点成立，那么每个单元格都会自动成为其自己的连接组件，并且组件计数恰好等于字母出现的次数。 

这将问题从连接构造问题简化为简单的计数和放置问题：我们只需要准确分配$a$细胞A，$b$单元格到 B，依此类推，同时确保相同字母不会出现相邻冲突。 

为了在结构上保证这一点，我们可以预先构建一个网格，其中在受控的单元划分内永远不会发生邻接。 实现此目的的标准方法是使用重复$2 \times 2$图案。 四个奇偶校验类别中的每一个都由$(i \bmod 2, j \bmod 2)$形成一组单元，其中没有两个单元是边缘相邻的。 这比棋盘着色更强：每个类本身就是网格图中的一个独立集合。 

一旦我们有了四个这样的独立集合，我们就可以将每个字母分配给一个类，并简单地从该类中选择所需数量的单元格。 由于每个班级在$50 \times 50$网格有625个cell，每个需求最多100个，容量从来不是问题。

 ## 算法演练

 我们将网格大小固定为$50 \times 50$。 它足够大，可以舒适地满足所有要求，同时仍然遵守限制。 

1. 根据坐标将所有单元格分为四组：$(i \bmod 2, j \bmod 2)$。 这将创建四组不相交的单元格。 每个集合都具有这样的属性：其中没有两个单元共享边缘。 这是消除连接问题的结构性保证。 
2. 对于四个字母 A、B、C 和 D 中的每一个，将其与这些奇偶校验类别之一相关联。 分配可以是任意的，因为所有班级都有足够的容量。 
3. 对于每个字母，从其指定类别中取出第一个所需数量的位置，并用该字母填充这些单元格。 由于类中的每个单元都与同一类中的所有其他单元隔离，因此每个填充单元都成为单个连接的组件。 
4. Fill all remaining cells arbitrarily, for example with any letter, but to avoid accidental merges, it is simplest to continue respecting the same parity-based structure and distribute leftover cells consistently within their classes.

 它之所以有效，归根结底是因为同一奇偶校验类别的两个单元格都不边缘相邻。 因为我们从不将字母放置在同一类中的两个相邻单元格中，所以字母的每次出现都是孤立的。 因此，每个字母的连通分量数量恰好等于我们放置它的次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b, c, d = map(int, input().split())

    n, m = 50, 50
    grid = [['A'] * m for _ in range(n)]

    # four parity classes
    classes = [[] for _ in range(4)]
    for i in range(n):
        for j in range(m):
            classes[(i % 2) * 2 + (j % 2)].append((i, j))

    req = [('A', a), ('B', b), ('C', c), ('D', d)]

    idx = 0
    for ch, cnt in req:
        cells = classes[idx]
        for k in range(cnt):
            i, j = cells[k]
            grid[i][j] = ch
        idx += 1

    print(n, m)
    for row in grid:
        print(''.join(row))

if __name__ == "__main__":
    solve()
```实施首先修复一个$50 \times 50$网格并预先计算四个奇偶校验类别。 每个类都是一个坐标列表，保证在网格图中相互不相邻。 

然后，我们将每个字母分配给一个类，并准确填充该类所需的单元格数量。 因为班级规模很大，所以我们永远不会缺位置。 

重要的微妙之处在于我们永远不会在类中混合字母。 混合会重新引入邻接约束，并可能无意中合并组件。 

## 工作示例

 考虑样本输入$5, 3, 2, 1$。 我们仍然建立一个$50 \times 50$网格，但只有前 11 个选定的位置很重要。 

| 步骤| 放置 | B 放置 | C 放置 | D 放置 |
 | ---| ---| ---| ---| ---|
 | 开始| 0 | 0 | 0 | 0 |
 | 在A之后| 5 | 0 | 0 | 0 |
 | 乙后| 5 | 3 | 0 | 0 |
 | C 之后 | 5 | 3 | 2 | 0 |
 | 后 D | 5 | 3 | 2 | 1 |

 每个位置都出现在不同的独立集合中，因此字母中不会出现任何邻接关系。 

现在考虑这样的情况$1, 1, 1, 1$。 每个字母在其各自的奇偶校验类中都有一个单独的单元，因此所有四个组件都是普通的单例。 网格仍然完全有效，因为未使用的单元不会影响已使用单元的连接性。 

这些痕迹表明，算法的行为仅取决于计数，而不取决于奇偶校验分离之外的几何形状。

 ## 边缘情况

 主要的边缘情况是一种颜色占主导地位的情况，例如$a=100$1. 简单的放置策略通常会在这里失败，因为它试图将许多相同颜色的单元打包到一个小区域中，并意外地将它们合并。 在这种结构中，每个 A-cell 都处于独立的奇偶校验类别中，因此即使 100 个 A-cell 仍然是 100 个独立的组件。 

另一种情况是所有值都相等。 贪婪的行填充方法会意外地创建长水平链，合并组件。 在这里，邻接在结构上在类内是不可能的，因此相等不会影响正确性。 

最后，当所有值都达到最大值时，$100,100,100,100$，紧密的网格结构可能会面临空间不足或被迫相邻的风险。 固定的$50 \times 50$布局保证了每个独立组有足够的容量，因此即使是最坏的情况也能安全地容纳。
