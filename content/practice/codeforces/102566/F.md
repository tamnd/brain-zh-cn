 ## 解决方案
 ## 问题理解

 我们有一行整数，需要将该行按非降序排序。 唯一可用的操作是选择行的连续部分并仅对该部分进行排序。 消耗的能量仅取决于所选部分的长度，以及一段长度`k`成本`k³`。 任务是找到所需的最小总能量。 

第一个有用的观察是，我们只关心其值还不是最终排序数组中应有的值的位置。 包含正确值的位置不需要被触及，但每个不正确的位置必须包含在至少一个操作中。 

输入尺寸很大。 单个测试用例最多可以包含`100000`所有测试用例的数量和总大小可以达到`2000000`。 这排除了任何涉及尝试多个间隔或对位置进行动态规划的事情，因为即使`O(n²)`会太慢了。 我们需要一个在排序后扫描数组恒定次数的解决方案。 

有几个案例很容易被忽视。 如果数组已经排序，则答案为零，因为不需要任何操作。 

例如：```
1
5
1 2 3 4 5
```答案是：```
0
```总是为整个数组创建操作的粗心解决方案将返回正值。 

另一个重要的情况是错误的位置被正确的位置分开。```
1
4
2 1 1 3
```排序后的数组是`[1,1,2,3]`，所以位置 1 和 3 是不正确的。 它们不能被视为一系列连续的错误头寸。 最佳解决方案使用两个长度为 2 的操作，一个覆盖位置 1 和 2，另一个覆盖位置 2 和 3，成本为`8 + 8 = 16`。 

仅计算连续错误块的长度的解决方案将错误地忽略这种可能性。 

## 方法

 一种直接的方法是尝试每个间隔，对其进行排序，然后查看哪个操作序列给出最小的能量。 这是正确的，因为每个允许的移动都是明确模拟的。 然而，有`O(n²)`间隔，并且每次模拟都需要额外的工作。 为了`n = 100000`，这是完全不可能的。 

关键的观察来自于逆过程的观察。 想象一下从排序数组开始并应用我们的操作的逆操作。 反向操作可以任意重新排列所选间隔，因为正向操作只是对其进行排序。 因此，需要包含在反向操作中的唯一位置是与最终排序排列不同的位置。 

现在考虑成本函数。 一段长度`k`成本`k³`。 长度大于二的段永远不会比用更小的段替换它更好。 例如，长度为 3 的段成本`27`，而两个长度为 2 的段的成本`16`。 一般来说，覆盖长度`k`与相邻对成本的间隔`8 * ceil(k / 2)`，它总是小于`k³`为了`k >= 3`。 

这将问题简化为一个简单得多的问题。 我们只需要选择相邻的位置对，使得每个不正确的位置都被至少一对覆盖。 每对选择的价格都是准确的`8`。 

对于连续运行不正确的长度位置`k`，所需的最小相邻对数为`ceil(k / 2)`。 游程不会交互，因为两个游程之间的正确位置仍然可以用作孤立的错误位置的邻居，但它不能减少另一个游程内所需的对的数量。 扫描不正确的位置并计算这些对就可以得到答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) 或更糟 | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 创建数组的排序副本。 将每个原始位置与其在排序副本中的值进行比较，并标记该位置是否不正确。 这些是操作必须覆盖的唯一位置。 
2. 扫描错误位置的布尔数组。 每当发现连续的错误位置时，令其长度为`len`。 本次运行需要`ceil(len / 2)`相邻操作，因为每个操作最多可以覆盖两个位置。 
3. 添加`8 * ceil(len / 2)`每次运行的答案。 长度为 2 的操作成本`2³ = 8`，因此将所需对的数量乘以八即可得出总能量。 
4.输出累积的能量。 

为什么它有效：

 每个不正确的位置必须至少出现在一个选定的区间内。 由于长度超过 2 的间隔总是比将它们分成长度为 2 的间隔更昂贵，因此最佳解决方案仅使用相邻对。 运行的`len`不正确的位置至少需要`ceil(len / 2)`对，因为每对最多覆盖两个位置。 使用交替相邻对的构造达到了这个下限，因此对的数量是最少的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        b = sorted(a)

        wrong = [a[i] != b[i] for i in range(n)]

        cost = 0
        i = 0
        while i < n:
            if not wrong[i]:
                i += 1
                continue

            j = i
            while j < n and wrong[j]:
                j += 1

            length = j - i
            cost += ((length + 1) // 2) * 8
            i = j

        ans.append(str(cost))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```排序后的副本仅用于识别哪些位置已经正确。 该算法从不修改数组，因为不需要实际的操作序列，只需要最小能量。 

扫描发现错误位置的最大运行次数。 表达式`(length + 1) // 2`计算游程长度一半的上限，避免浮点运算。 Python 整数还可以避免溢出，因为最大可能的答案完全在其范围内。 

边界条件由两个 while 循环处理。 在最后一个位置结束的运行会被正确处理，因为内循环在以下情况下停止：`j == n`。 

## 工作示例

 对于样本：```
1
4
2 1 4 3
```排序后的数组是`[1,2,3,4]`。 错误的位置全部是四个位置。 

| 索引 | 错误| 当前运行长度| 增加成本|
 | ---| ---| ---| ---|
 | 1 | 是的 | 4 | 0 |
 | 2 | 是的 | 4 | 0 |
 | 3 | 是的 | 4 | 0 |
 | 4 | 是的 | 完成 | 16 | 16

 游程长度为`4`，所以需要`ceil(4/2)=2`相邻的操作。 成本是`2 * 8 = 16`。 

一个单独的例子：```
1
4
2 1 1 3
```排序后的数组是`[1,1,2,3]`。 

| 索引 | 价值| 排序值 | 错误|
 | ---| ---| ---| ---|
 | 1 | 2 | 1 | 是的 |
 | 2 | 1 | 1 | 没有|
 | 3 | 1 | 2 | 是的 |
 | 4 | 3 | 3 | 没有|

 有两条长度为一的游程。 

| 运行| 长度| 所需对 | 成本|
 | ---| ---| ---| ---|
 | 第一个错误的位置| 1 | 1 | 8 |
 | 第二个错误位置| 1 | 1 | 8 |

 最终的答案是`16`。 这个例子说明了为什么只计算连续的错误块是不够的。 单个错误位置仍然需要与邻居配对。

 ## 边缘情况

 对于已经排序的数组，例如：```
1
5
1 2 3 4 5
```每次与排序副本的比较都会成功。 扫描永远不会进入错误位置运行，因此答案仍然为零。 

对于分离的错误位置：```
1
4
2 1 1 3
```该算法会进行两次长度为 1 的游程。 每次运行都会贡献一个相邻的对，给出`8 + 8 = 16`。 中间的正确位置允许包含在两个操作中，这就是为什么两个不正确的位置仍然可以被修复。 

对于连续错误段：```
1
6
6 5 4 3 2 1
```所有六个位置都不正确。 游程长度为 6，因此根据公式，三个相邻操作就足够了。 答案是`3 * 8 = 24`。 该算法不会尝试使用较大的区间，因为立方成本会大得多。
