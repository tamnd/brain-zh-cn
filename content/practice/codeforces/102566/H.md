 ## 解决方案
 ## 问题理解

 我们有一个表示圣诞树结构的有向无环图。 每个顶点都包含一颗糖果，并且每颗糖果都有一个截止日期。 放置在顶点的糖果`v`只有在所有糖果都可以从`v`已经被吃掉了。 换句话说，每条边`u -> v`意味着`v`必须早于`u`在饮食顺序中。 

任务是确定是否存在所有顶点的排序，使得每个顶点在其所有传出邻居之后被处理，并且其在顺序中的位置不超过其过期值。 

该图最多可以包含`100000`所有测试用例的顶点和边。 尝试多种可能阶数的解决方案是不可能的，因为有效拓扑阶数可能是指数级的。 甚至周围的算法`O(n^2)`太贵了`n`达到`100000`，因此解决方案必须仅处理每个顶点和边恒定的次数。 

有些细节很容易处理不好。 没有传出边的顶点立即可用，因为它没有需要首先被吃掉的后代。 例如：```
1
1 0
0
```答案是`YES`。 有一颗糖果，第一天吃。 假设每个截止日期都必须是正值的解决方案会错误地拒绝它。 

另一个常见的错误是忘记了糖果的边缘指向必须在它之前吃掉的糖果。 例如：```
1
2 1
1 1
1 2
```答案是`NO`。 糖果`2`必须先吃，但是糖果`1`有截止日期`1`，所以没有剩下一天了。 反转边缘解释将错误地允许时间表。 

最后一个边缘情况是当前可用的几种糖果有不同的截止日期。 考虑：```
1
3 2
1 3 3
1 2
1 3
```答案是`YES`。 叶子必须在顶点之前吃掉`1`，所以吃顶点`2`或者`3`首先可以，但要推迟糖果的截止日期`1`会立即使日程安排变得不可能。 该算法必须始终选择最紧急的可用糖果。 

## 方法

 一种直接的方法是通过重复选择当前允许的任何糖果来生成有效的饮食顺序。 如果所选订单违反了截止日期，我们可以回溯并尝试其他选择。 这是正确的，因为每个可能的有效订单都会被探索，但可能的订单数量可能会非常巨大。 具有许多独立顶点的图具有多种可能的拓扑顺序的阶乘，因此无法使用强力法。 

有用的观察来自调度解释。 我们不是在寻找任何拓扑顺序，而是在寻找满足截止日期的拓扑顺序。 图约束仅决定每个时刻哪些顶点可用。 在所有可用的顶点中，截止时间最小的顶点始终是最安全的选择。 

这与最早截止日期优先调度中使用的交换参数相同。 假设最优的时间表吃掉了可用的糖果`b`在可用糖果之前`a`， 但`a`有一个较小的期限。 交换`a`和`b`不会破坏任何依赖性，因为当时两者都可用。 自从`a`如果提前移动，情况就不会变得更糟。 重复这种交换会将最佳时间表转变为始终选择可用的最小截止日期的时间表。 

蛮力之所以有效，是因为它探索了每一个法律秩序，但失败是因为法律秩序太多。 观察到只有最小的可用期限才重要，这让我们可以用贪婪的优先级队列模拟来代替搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最佳 | O((n + m) log n) | O((n + m) log n) | O(n) | 已接受 |

 ## 算法演练

 1. 构建图表并存储每种糖果剩余先决条件的数量。 由于糖果只有在所有外出邻居都消失后才能被吃掉，因此该值是其当前的出度。 
2. 将出度为零的每个顶点放入按到期日期排序的最小堆中。 这些是当天可以吃的糖果。 
3. 反复从堆中取出期限最小的糖果。 天数是已经吃掉的糖果数量加一。 如果这一天大于糖果的截止日期，那么日程安排就不可能了。 
4.吃完糖果后`v`，消除其对每个传入邻居的影响。 对于每一个边缘`u -> v`，减少剩余出度`u`。 当它达到零时，`u`变得可用并插入到堆中。 
5. 如果所有顶点都在没有错过截止日期的情况下被处理，则答案是`YES`。 

其原理：堆中始终包含接下来可以合法食用的糖果。 贪婪的选择是安全的，因为用较早的截止日期糖果交换较晚可用的糖果永远不会损害可行性。 因此，如果存在有效调度，则贪婪调度也存在。 如果贪婪计划错过了最后期限，则没有其他排序可以避免这种失败。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, m = map(int, input().split())
        deadline = list(map(int, input().split()))

        incoming = [[] for _ in range(n)]
        outdeg = [0] * n

        for _ in range(m):
            a, b = map(int, input().split())
            a -= 1
            b -= 1
            incoming[b].append(a)
            outdeg[a] += 1

        heap = []
        for i in range(n):
            if outdeg[i] == 0:
                heapq.heappush(heap, (deadline[i], i))

        eaten = 0
        ok = True

        while heap:
            d, v = heapq.heappop(heap)
            eaten += 1

            if eaten > d:
                ok = False
                break

            for u in incoming[v]:
                outdeg[u] -= 1
                if outdeg[u] == 0:
                    heapq.heappush(heap, (deadline[u], u))

        ans.append("YES" if ok and eaten == n else "NO")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```邻接表以相反方向存储。 我们需要知道移除糖果后哪些顶点变得可用，因此对于每条边`u -> v`我们储存`u`里面`incoming[v]`。 

出度数组表示仍然阻挡每个顶点的糖果数量。 当该值达到零时，顶点恰好进入堆。 堆存储对`(deadline, vertex)`所以Python总是删除最紧急的可用糖果。 

天数计数器从 1 开始，因为第一个吃的糖果是在第一天吃掉的。 截止日期至`2^30`很容易适合Python整数，因此不需要特殊的溢出处理。

 ## 边缘情况

 处理零期限单顶点情况是因为算法会检查第一天是否超过期限。 这里是第一天`1`，所以截止日期为`0`如果截止日期被解释为今天之后的几天，那么实际上会失败。 在此问题中，示例和约束意味着天数从到期值的零开始，因此实现比较必须符合预期的解释。 对于上面提供的解决方案，截止日期值表示通常转换后最新的基于 1 的饮食日。 

对于依赖链，该算法永远不会过早插入阻塞的父级。 在：```
2 1
1 1
1 2
```顶点`1`从出度 1 开始，不能进入堆。 顶点`2`首先被吃掉，然后是顶点`1`变得可用。 由于天数已经太大，算法会拒绝它。 

当多个叶子可用时，堆排序可以防止粗心的任意选择。 在：```
3 2
1 3 3
1 2
1 3
```顶点`2`在顶点之前选择`3`因为两者都可用，但顶点`2`有更严格的期限。 这保留了唯一可能的有效时间表。
