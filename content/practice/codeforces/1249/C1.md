 ## 解决方案
 ## 问题理解

 我们正在研究可以使用非常具体的构建系统分解的数字：三的幂，其中每个幂最多可以使用一次。 将每个数字视为由大小为 1、3、9、27、81 等的“块”构建而成，每个块可以被占用或不被占用，并且不会重复。 

如果我们可以选择这些块的子集，并且其总和恰好等于该数字，则该数字是有效的。 任务是，对于每个查询值`n`，找到大于或等于的最小有效数`n`。 

输入大小足够小`n`最多 10,000 个，最多 500 个查询。 这立即告诉我们，我们不需要任何高级数据结构或繁重的预计算。 即使每个查询的线性扫描也能轻松通过，因为检查候选号码的成本很低。 

主要的微妙之处在于许多整数在约束下无法表示。 一种幼稚的方法可能会尝试贪婪地减去三的幂或尝试直接构造表示，但这会失败，因为该表示相当于一个基数为 3 的系统，其数字限制为`0`或者`1`。 关键的困难在于某些数字需要以 3 为基数进行进位，而“进位”可能会使数字无效并强制跳转到下一个有效结构。 

朴素推理的一个常见失败案例是假设，一旦一个数字看起来接近 3 的不同幂的总和，它就可以在本地修复。 例如，`20`接近于`18 + 1 + 1`，但是重复`3^0`是不允许的，修复它需要跳转到完全不同的规模，而不是在本地修补。 

## 方法

 蛮力策略很简单：从`n`并一一检查每个整数，测试它是否可以写成三的不同幂的和。 测试一个数字`x`，我们反复减去不超过的三的最大幂`x`，将其标记为已使用，并确保我们永远不会重复使用电源。 这有效地模拟了检查以 3 为基数的表示形式是否仅包含数字`0`或者`1`。 

这是有效的，因为表示相当于写作`x`以 3 为基数并验证没有数字等于`2`。 然而，更直接的是，我们可以重复除以 3 并检查余数。 

蛮力方法是正确的，但在最坏的情况下可能会很慢，因为我们可能需要向上扫描许多数字才能找到有效的数字。 有效数字的结构提出了一个更好的观点：有效数字正是那些以 3 为基数表示仅包含数字的数字`0`和`1`。 这意味着之后的下一个有效数字`n`本质上是下一个以 3 为基数表示形式为“类似二进制”的整数。 

这将问题转化为在受限数字系统中生成下一个数字。 我们可以生成安全范围内的所有有效数字，而不是检查每个整数（因为`3^10`已经超过 59000，我们只需要最多 10000），然后通过二分搜索回答每个查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(Q × K × log N) 最坏情况 | O(1) | O(1) | 可以接受但没有必要 |
 | 预先计算有效数字+二分查找| O(P log P + Q log P) | O(P log P + Q log P) | O(P)| 已接受 |

 这里`P`是达到最大所需范围的有效数字的数量。 

## 算法演练

 1. 使用 3 的幂的 DFS 生成所有有效数字，其中每个幂都被包含或排除。 

每个递归步骤决定是否采取`3^k`或不。 这是有效的，因为每个有效数字都对应于 3 的幂的唯一子集。 
2. 一旦构造的数字超过安全上限，例如此问题的 10^9 或至少 59000，则停止递归。 

此修剪是有效的，因为所有查询值都以 10^4 为界。 
3. 将所有生成的数字存储在一个列表中并对其进行排序。 

需要排序是因为 DFS 不按数字顺序生成它们。 
4. 对于每个查询`n`，找到列表中大于或等于的最小数字`n`使用二分查找。 
5. 输出该值。 

关键的设计选择是首先生成所有候选者。 这避免了重复检查，并将每个查询变成简单的搜索。 

### 为什么它有效

 每个有效数字都精确对应于 3 的不同幂的子集。 相反，每个子集都会产生一个有效的数字。 这在有效数字和二进制字符串之间在 3 进制数字的位置上建立了双射。 因此，生成 3 的幂的所有子集（直到极限）将所有有效数字精确地枚举一次，并对它们进行排序会生成回答任何查询所需的所有候选者的完整有序集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

vals = []

# generate all sums of distinct powers of 3
def dfs(i, current):
    if current > 10**9:
        return
    if i > 20:
        vals.append(current)
        return

    # do not take 3^i
    dfs(i + 1, current)

    # take 3^i
    dfs(i + 1, current + (3 ** i))

dfs(0, 0)
vals = sorted(set(vals))

q = int(input())
for _ in range(q):
    n = int(input())
    # linear scan is fine due to small size, but binary search is cleaner
    l, r = 0, len(vals)
    while l < r:
        m = (l + r) // 2
        if vals[m] >= n:
            r = m
        else:
            l = m + 1
    print(vals[l])
```DFS 构造通过选择或跳过 3 的每个幂形成的所有数字。 深度限制`i > 20`是安全的，因为`3^20`已经远远超出了所需的最大值。 这`set`删除可确保消除重复项，尽管在此构造中实际上不会发生重复项。 

即使列表大小大于预期，二分搜索步骤也可确保有效回答每个查询。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    vals = []

    def dfs(i, current):
        if current > 10**9:
            return
        if i > 20:
            vals.append(current)
            return
        dfs(i + 1, current)
        dfs(i + 1, current + (3 ** i))

    dfs(0, 0)
    vals = sorted(set(vals))

    q = int(input())
    out = []
    for _ in range(q):
        n = int(input())
        l, r = 0, len(vals)
        while l < r:
            m = (l + r) // 2
            if vals[m] >= n:
                r = m
            else:
                l = m + 1
        out.append(str(vals[l]))
    return "\n".join(out)

assert run("1\n2\n") == "3"

 ## 边缘情况

 对于`n = 1`，DFS 包括`1 = 3^0`直接，所以二分查找立即返回 1。 

对于`n = 2`，不存在使用三的不同幂的表示，因此预先计算的列表完全跳过它。 下一个有效条目是 3，对应于`3^1`。 该算法自然地处理这个问题，因为二分搜索不假设连续性。 

为了`n = 10000`，搜索落在下一个可表示的数字上，即 19683。这表明该算法完全依赖于预先计算的结构而不是增量检查，正确地跨越了不存在有效数字的大间隙。
