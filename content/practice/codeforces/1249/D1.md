[CF 1249D1 - 段太多（简单版）](https://codeforces.com/problemset/problem/1249/D1)

 **评分：** 1800
 **标签：** 贪婪
 **求解时间：** 5m 17s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们在数轴上得到了整数区间的集合。 每个区间表示其范围内所有整数点的覆盖范围。 如果一个点被超过多个覆盖，那么它就会成为问题$k$同时间隔。 任务是删除尽可能少的间隔，以便整数点不会被超过$k$剩余间隔。 

换句话说，我们要删除一些间隔，以便每个整数坐标处的最大重叠永远不会超过$k$，同时最小化我们删除的间隔数量。 

坐标范围很小，最多 200 个，间隔数量也最多 200 个。这强烈表明解决方案可以显式模拟所有整数点的覆盖范围，并且仍然保持高效。 任何迭代所有段和所有坐标的方法都是可以接受的，但是段子集中任何指数的方法都将是不必要的过度杀伤力。 

当许多间隔完全重叠在一个点上时，会出现微妙的边缘情况。 例如，如果所有间隔都是$[1, 200]$和$k = 1$，那么必须删除第一个间隔之外的每个附加间隔。 仅查看端点而不跟踪每个点的当前重叠的贪婪解决方案将会失败，因为冲突是按整数坐标定义的，而不是按线段端点定义的。 

另一种故障模式来自于删除段而不考虑它们在多个点上的贡献。 一段在一个坐标上可能看起来无害，但却是超出的原因$k$在另一个坐标处。 

## 方法

 直接的暴力想法是尝试段的所有子集，检查剩余的集合是否满足约束，并选择具有最大大小的子集。 对于每个子集，我们将计算从 1 到 200 的每个整数点的覆盖范围，并验证没有点超过$k$。 这是正确的，因为它探索了每一种可能的删除选择。 

问题是子集的数量是$2^n$，即使对于$n = 200$。 即使检查子集仅花费$O(n \cdot 200)$，总的工作是完全不可行的。 

关键的结构观察是违规是局部于各个整数点的。 如果某个点$x$被覆盖超过$k$段，那么我们只需要删除有助于覆盖的段$x$。 这表明了一种贪婪的策略，该策略独立地解决每个坐标处的冲突，但仔细协调，以便在某一点上的删除也可以修复未来的违规行为。 

我们从左到右处理点。 在每个点，我们维护覆盖它的活动段集。 如果活动段数超过$k$，我们必须删除其中一些。 最佳选择是删除向右延伸最远的线段。 这种选择尽可能积极地减少未来的重叠，因为长段继续对许多即将到来的点做出贡献。 

这种贪婪策略之所以有效，是因为一旦我们确定了一个点$x$，我们确保不超过$k$区间覆盖$x$保留，并通过删除最右端点的间隔，我们可以最小化后续坐标上的未来“压力”。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n \cdot n \cdot 200)$|$O(n)$| 太慢了 |
 | 贪心扫 |$O(n \cdot 200 \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 对于从 1 到 200 的每个整数坐标，维护当前哪些段覆盖它。 由于约束很小，我们可以有效地重新计算。 
2. 在每个坐标处$x$，收集覆盖的所有段$x$并且仍然没有被删除。 该集合代表此时的当前重叠。 
3. 如果活动段数为$x$至多是$k$，移动到下一个坐标，因为约束已经满足。 
4. 如果有超过$k$活动段，我们必须删除其中一些。 为了最大限度地减少未来的冲突，请选择具有最大右端点的线段。 删除足够多的段，以便仅$k$保持活跃于$x$。 
5. 全局标记已删除的线段，以便在以后的所有坐标中忽略它们。 
6. 对 200 以内的所有坐标继续此过程。 

为什么它有效：在任何坐标$x$，如果超过$k$间隔覆盖它，至少其中一个必须被删除。 删除具有最大右端点的区间是安全的，因为它消除了对未来覆盖范围贡献最大的区间。 任何保留较长间隔而放弃较短间隔的替代删除都无法提高未来的可行性，并且可能只会增加以后的冲突。 在每个坐标处重复这种局部最优修复可确保每个点在失效后立即得到修复，并且删除不会在较早的点重新引入违规，因为我们只删除间隔，从不添加它们。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    seg = [None] * n

    for i in range(n):
        l, r = map(int, input().split())
        seg[i] = (l, r)

    removed = [False] * n

    for x in range(1, 201):
        active = []
        for i, (l, r) in enumerate(seg):
            if not removed[i] and l <= x <= r:
                active.append(i)

        if len(active) <= k:
            continue

        active.sort(key=lambda i: seg[i][1], reverse=True)

        for j in range(len(active) - k):
            removed[active[j]] = True

    ans = [i + 1 for i in range(n) if removed[i]]
    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```该解决方案显式模拟每个整数坐标处的覆盖范围。 对于每个点，它都会构建当前活动段的列表，并通过删除多余的段来强制执行约束。 按右端点排序可确保我们删除那些会继续影响未来坐标的线段，这是中心贪婪选择。 

一个微妙的实现细节是在每个坐标处从头开始重新计算活动段。 尽管它看起来效率低下，但边界足够小，因此这是安全的，并且避免了维护动态区间集的复杂性。 

## 工作示例

 ### 示例 1

 输入：```
n = 4, k = 1
[1,3], [2,5], [2,4], [3,6]
```我们逐点跟踪覆盖范围。 

在$x=2$，所有四个段均处于活动状态。 我们必须删除其中的 3 个，只保留我们尽可能保留的那些中右端点最小的一个。 

| x| 活跃段 | 行动| 删除 |
 | ---| ---| ---| ---|
 | 2 | 1,2,3,4 | 保留 1，删除 2,3,4 | 2,3,4 |
 | 3 | 1,4| 好的 | 2,3,4 |
 | 4 | 4 | 好的 | 2,3,4 |

 这表明早期积极清除可以防止未来的过载。 

### 示例 2

 输入：```
n = 3, k = 2
[1,2], [1,2], [1,2]
```在$x=1$, all three are active.

 | x| 活跃段 | 行动| 删除 |
 | ---| ---| ---| ---|
 | 1 | 1,2,3 | keep 1,2 remove 3 | 3 |
 | 2 | 1,2 | 好的 | 3 |

 这证实了只需要删除一个，并且贪婪保留任意两个，因为所有的效果都是等效的。

 ## 边缘情况

 所有线段重合的情况表明算法在每个点重复修剪多余的部分。 在$x=1$，所有段均处于活动状态，因此仅$k$保留，其余标记为删除。 由于删除的线段永远不会重新出现，因此所有后续坐标将自动保持有效。 

稀疏非重叠配置表明该算法永远不会删除任何不必要的内容。 在每个坐标处，活动计数永远不会超过$k$，因此移除分支永远不会触发，并且输出保持为空。 

最坏情况的重叠链，其中段交错但在相邻点上连续重叠，迫使重复贪婪修剪。 该算法一致地删除具有最右端点的线段，确保未来的重叠尽快减少并防止级联违规。
