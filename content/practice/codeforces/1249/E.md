 ## 解决方案
 ## 问题理解

 我们得到一栋从 1 层到 n 层的建筑物。 在相邻楼层之间移动可以通过两种不同的方式完成：楼梯或电梯。 楼梯的每层成本为 a[i]，电梯的每层成本为 b[i]，加上每次开始乘坐电梯时的固定开销 c。 

一个关键细节是单次移动不限于相邻楼层。 从任何 x 层，您可以一次跳到任何 y 层，支付通过楼梯或电梯模型穿过所有中间楼层的费用。 到达楼层后，您可以开始另一次移动，可能会再次切换模式。 

任务是计算每个楼层 i 从第 1 层开始到达 i 所需的最小可能总时间。 

该结构本质上是 n 个节点上的图，其中每对楼层都通过两条加权路径连接：一条路径由 a 的前缀和定义，另一条路径由 b 的前缀和加上固定成本 c 定义。 挑战在于，尽管图的描述很密集，但权重是结构化的。 

约束 n 高达 200000 和值高达 1000 意味着对楼层对的任何二次方法都是不可能的。 解决方案必须是线性或接近线性的，可能为 O(n) 或 O(n log n)。 这强烈建议动态规划或两种状态最短路径解释。 

当考虑多次移动时，会出现一个微妙的问题。 一个天真的假设是，人们应该始终使用楼梯或电梯直接从 1 楼移动到 i 楼。 这是不正确的，因为中间切换可以降低成本。 

例如，假设电梯对于早期楼层来说很便宜，但楼梯后来变得更便宜。 天真的直接比较忽略了您可以在中间楼层切换模式。 

另一个边缘情况是当 c 很大时。 那么，电梯对于小段来说永远不是最佳的，但如果与之前的状态积累相结合，对于长跳跃来说仍然可能有用。 

真正的复杂之处在于，每个楼层可以通过两种“模式”到达，具体取决于最后一次移动是使用楼梯还是电梯，因为未来的成本通过累积收益隐含地取决于该选择。 

## 方法

 强力方法会将其视为 n 个节点的完整图上的最短路径问题。 对于每一对 (x, y)，我们使用前缀和以 O(1) 的时间计算楼梯和电梯成本。 然后我们从节点 1 运行 Dijkstra。 

该图有 O(n^2) 条边，因此 Dijkstra 变为 O(n^2 log n)，这对于 n 高达 200000 来说太慢了。甚至存储边也是不可能的。 

关键的观察结果是，成本结构是沿线累加的，因此转换仅取决于前缀差异。 更重要的是，电梯每次使用都会产生固定的罚金，这使得重复切换成本高昂，除非它可以在许多楼层上摊销。 

我们可以将这个过程解释为每层楼维持两种状态：如果最后一次移动使用楼梯，以及如果最后一次移动使用电梯，则到达 i 层的最佳成本。 从第 i 层的状态开始，我们可以通过支付分段成本扩展到任何 j > i 或 j < i。 然而，我们观察到最佳转换可以压缩为线性转换，而不是重新计算所有对，因为按增加的楼层顺序移动允许前缀松弛。 

这导致了动态编程解决方案，我们扫地并在通过楼梯或电梯延伸时保持最佳可实现的成本。 电梯状态会累积一个额外的 c，因此它的行为就像带有惩罚的重置。 

这种减少之所以有效，是因为任何最佳的移动序列都可以重新排列成沿线的单调改进序列，从而无需重新访问任意对。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（所有对最短路径）| O(n^2 log n) | O(n^2 log n) | O(n^2) | O(n^2) | 太慢了 |
 | 具有两种状态 + 线性转换的 DP | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们维护两个数组。 如果我们最后使用了最后使用的楼梯过渡，则表示到达每一层的最佳成本。 另一个表示相同，但​​以电梯过渡结束。 

我们还维护 a 和 b 的前缀和以快速计算段成本。 

### 步骤

 1. 计算楼梯和电梯费用的前缀总和。 

这使我们能够在 O(1) 中评估任何段成本，这是必要的，因为转换可能跨越多个楼层。 
2. 将 dp_s[i] 定义为以“楼梯一致”方式到达楼层 i 的最低成本，并且 dp_e[i] 与电梯使用类似。 

这种分离是必要的，因为电梯转换包含影响未来决策的固定开销。 
3. 初始化 dp_s[1] = dp_e[1] = 0。 

从第 1 层开始不会产生任何成本，也没有先前的模式限制。 
4. 将楼层从 2 扫到 n，使用之前的最佳状态更新 dp 值。 

对于每个 i，考虑通过楼梯或电梯从任何先前的 j < i 延伸。 
5. 对于楼梯过渡，使用 prefix_s[i] - prefix_s[j] 计算从 j 到 i 的成本。 

不要检查所有 j，而是保持 dp_s[j] - prefix_s[j] 的运行最小值，它代表楼梯的最佳入口点。 
6. 对于电梯转换，计算成本为 dp_*[j] + c + (prefix_b[i] - prefix_b[j])。 

类似地，维持 dp_e[j] - prefix_b[j] 的运行最小值，因为电梯会独立于段长度添加恒定开销 c。 
7. 将 dp_s[i] 和 dp_e[i] 作为所有有效转换的最小值。 

这确保我们始终保持到达 i 层的最佳方式。 
8. 第 i 层的答案是 min(dp_s[i], dp_e[i])。 

最后一层的模式并不重要； 只有总成本才重要。 

### 为什么它有效

 关键的不变量是，对于任何楼层 i，dp_s[i] 和 dp_e[i] 表示以相应的最后转换类型结束于 i 的所有有效移动序列中的最佳成本。 因为每个转移成本都分解为前缀差加上常数项（仅在电梯情况下），所以从任何 j 到 i 的转移都可以重写为仅取决于 j 的候选值加上仅取决于 i 的项。 这种可分离性允许维护前缀最小值而不是枚举所有 j。 由于每条最优路径都可以分解为单调段，其成本仅取决于端点，因此这种松弛不会错过任何最优解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, c = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    ps_a = [0] * (n + 1)
    ps_b = [0] * (n + 1)

    for i in range(1, n):
        ps_a[i + 1] = ps_a[i] + a[i - 1]
        ps_b[i + 1] = ps_b[i] + b[i - 1]

    INF = 10**18

    dp_s = [INF] * (n + 1)
    dp_e = [INF] * (n + 1)

    dp_s[1] = dp_e[1] = 0

    best_s = 0
    best_e = 0

    res = [0] * n
    res[0] = 0

    for i in range(2, n + 1):
        dp_s[i] = min(dp_s[i], ps_a[i] + best_s)
        dp_e[i] = min(dp_e[i], ps_b[i] + c + best_e)

        best_s = min(best_s, dp_s[i] - ps_a[i])
        best_e = min(best_e, dp_e[i] - ps_b[i])

        res[i - 1] = min(dp_s[i], dp_e[i])

    print(*res)

if __name__ == "__main__":
    solve()
```该代码完全依赖于前缀和来使段花费恒定的时间。 变量 best_s 和 best_e 存储过渡的最佳调整起点，有效地将所有可能的先前楼层压缩为单个候选值。 

一个常见的实现错误是在计算 dp[i] 之前更新 best_s 和 best_e，这将错误地允许自转换。 正确的顺序是首先使用以前的最佳值计算 dp[i]，然后用 i 更新它们。 

另一个微妙之处是将 best_s 和 best_e 初始化为零，因为 dp[1] - prefix[1] 等于零。 这会将两种过渡类型正确锚定在起始楼层。

 ## 边缘情况

 一种重要的情况是当电梯开销 c 非常大时。 在这种情况下，任何电梯转换都应该被最优解忽略，但算法仍然通过 dp_e 对其进行处理。 正确性来自于对两种状态取最小值，确保电梯永远不会污染楼梯最优结果。 

另一个极端情况是，与电梯相比，楼梯成本为零或非常小。 该算法自然有利于 dp_s，因为 best_s 很快变得更负，使得楼梯过渡主导所有未来的计算。 

最后一个微妙的情况是确保没有任何转换使用未来的信息。 更新的顺序保证 dp[i] 仅取决于先前楼层的状态，并且 best_s 和 best_e 仅在 dp[i] 最终确定后更新。 这可以防止人为的自我改进循环，否则会使 DP 解释无效。
