 ## 解决方案
 ## 问题理解

 每个孩子从一本书开始，每天所有的书都按照固定的排列同时传递。 如果一个孩子 i 将他们的书交给 p[i]，那么一天后，这本书会沿着这个有向边移动一步。 两天后，它沿着排列移动两步，依此类推。 

从一本起始书的角度来看，我们重复地应用相同的排列。 每个起始位置i的问题是：在进行了多少次排列之后，从i开始的书第一次回到i。 

这相当于询问有向图中包含节点 i 的循环长度，其中每个节点恰好有一个出边。 由于 p 是排列，因此该图是循环的不相交并集。 

约束很小：n 最多为 200，并且最多有 200 个查询。 这立即告诉我们，即使每个测试用例使用 O(n²) 或 O(n³) 方法也是安全的。 除了简单的遍历和标记之外，我们不需要大量的优化或数据结构。 

一个微妙的边缘情况是节点映射到自身，即 p[i] = i。 在这种情况下，循环长度为 1，答案必须为 1。另一种情况是长循环，其中没有节点重复，直到完整循环完成，例如像 2 3 4 5 1 这样的排列，其中每个节点共享相同的答案 5。任何试图单独模拟每个节点的日常移动的错误解决方案可能仍然会由于小的约束而在这里工作，但存在效率低下或冗余重新计算的风险。 

## 方法

 直接模拟方法是采用每个起始索引 i 并重复应用排列，直到返回到 i，同时计算步数。 这是正确的，因为每一步都严格遵循传书规则。 然而，在最坏的情况下，长度为 n 的单个循环迫使每个起始节点执行 O(n) 个步骤，从而导致每个测试用例的执行时间为 O(n²)。 当 n 达到 200，q 达到 200 时，这仍然可以轻松通过（最坏情况下大约 800 万次操作），但它会大量重复工作，因为循环中的每个节点都会重新计算相同的遍历。 

关键的结构见解是排列分解为不相交的循环。 同一循环中的每个节点共享相同的返回时间，等于循环长度。 我们没有单独模拟，而是遍历每个循环一次，计算其大小，并将该大小分配给其中的所有节点。 这减少了冗余工作，并将解决方案转变为干净的图遍历问题。 

我们可以通过迭代所有节点并在遇到未访问过的节点时开始遍历来找到循环。 我们跟踪 p[i]、p[p[i]] 等，直到返回起点，计算该循环中有多少个节点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| 每次查询 O(n²) | O(1) 额外 | 已接受 |
 | 循环分解| 每个查询 O(n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个查询并构建答案数组。 

1. 维护一个初始化为 false 的大小为 n 的访问数组，以及一个初始化为零的答案数组。 访问过的数组确保我们不会多次处理同一个循环。 
2. 从 1 到 n 迭代每个节点 i。 如果 i 已经被访问过，则跳过它，因为它属于已经处理过的循环。 
3. 当我们找到未访问的节点 i 时，我们开始从 i 开始遍历循环。 我们存储起始节点并使用 p[current] 重复移动排列。 
4. 遍历时，我们将当前循环中的所有节点收集到一个列表中，并将它们标记为已访问。 我们还计算返回起始节点之前走了多少步。 
5. 一旦我们关闭循环（我们再次到达起点），我们将计算出的循环长度分配给收集列表中的每个节点。

我们显式收集节点而不是动态分配的原因是我们只有在完成遍历后才知道循环长度。 

### 为什么它有效

 排列中的每个节点恰好属于一个有向循环。 从任何未访问的节点开始的遍历都遵循确定性边，并且最终必须返回到起始节点，因为图是有限的并且每个节点只有一个传出边。 这保证了每次遍历都会发现一个完整的循环，没有分支或歧义。 由于答案被定义为第一次返回时间，这正是循环长度，因此将循环大小分配给该组件中的所有节点是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

q = int(input())
for _ in range(q):
    n = int(input())
    p = [0] + list(map(int, input().split()))
    
    visited = [False] * (n + 1)
    ans = [0] * (n + 1)
    
    for i in range(1, n + 1):
        if visited[i]:
            continue
        
        cycle = []
        cur = i
        
        while not visited[cur]:
            visited[cur] = True
            cycle.append(cur)
            cur = p[cur]
        
        length = len(cycle)
        for v in cycle:
            ans[v] = length
    
    print(*ans[1:])
```该解决方案的工作原理是将排列显式分解为循环。 1 索引简化了从输入到图节点的直接映射。 每个节点仅被访问一次，因此每个查询的遍历成本是线性的。 

一个常见的实现陷阱是在移动到循环中的下一个节点之前忘记将节点标记为已访问，这可能会导致错误实现中的无限循环。 另一个微妙的问题是混淆了自行车步行的终止条件； 我们依赖于在当前遍历中重新访问先前访问过的节点，这是安全的，因为每个节点都有一个出边。

 ## 边缘情况

 像 p[i] = i 这样的自循环会被自然地处理，因为遍历一次后会立即返回到起始节点，产生循环长度 1。访问过的标记确保我们正确停止而不会无限循环。 

所有节点连接在一个循环中的大循环也能正确处理，因为遍历会一直持续到我们重新访问起始节点为止，从而保证在分配之前完全覆盖循环。
