 ## 问题理解

 我们收到了几个独立的查询。 每个查询提供一个大整数$n$，我们必须输出最小的整数$m \ge n$这样$m$可以表示为 3 的不同幂的和。换句话说，每个有效数字都对应于从$1, 3, 9, 27, \dots$并对它们求和，每种幂最多允许一次。 

这种结构意味着每个好的数字本质上都是以 3 为基数的表示形式，其中数字仅限于 0 或 1。 如果任何数字 2 出现在三进制表示中，则该值不是直接有效的，我们必须将其“四舍五入”到下一个可表示的数字。 

输入约束$n \le 10^{18}$意味着我们可以安全地考虑 3 的幂最多大约$3^{38}$， 自从$3^{39}$已经超过$10^{18}$。 这将所有相关构造的状态空间限制为少于 40 个位置。 对于多达 500 个查询，任何与每个查询的位长度呈线性关系的解决方案都足够快。 

一个天真的想法是生成 3 的不同幂的所有有效和，然后搜索不小于的最小的和$n$。 然而，这样的总和的数量是$2^{40}$，太大了（大约一万亿种可能性）。 甚至生成或排序它们也是不可能的。 

如果我们试图贪婪地解释，就会出现更微妙的故障模式$n$以 3 为基数，只需将每个数字 2 替换为进位即可。 粗心的实现可能会在本地调整数字，而没有正确地将进位传播到更高的位置，从而产生仍然无效甚至小于的值$n$。 例如，如果我们看到像这样的数字模式$1\,2\,0$，仅固定 2 而不考虑与较低数字的交互可能会破坏单调性保证。 

## 方法

 蛮力方法枚举 3 至 3 次方的所有子集$3^{38}$，计算它们的总和，然后通过二分搜索此列表来回答每个查询。 这是正确的，因为它直接构造了整个有效数字集。 问题是子集空间随着幂数呈指数增长。 拥有大约 39 种可用能力，我们已经达到$2^{39}$，这在计算上是不可行的。 

关键的观察结果是有效性仅取决于三进制数字$\{0,1\}$。 这意味着我们永远不需要直接推理子集。 相反，我们以基数 3 为基础，并将问题视为受限数字系统：我们想要下一个数字，其三元表示不包含数字 2。 

这将任务转化为数字纠正问题，类似于用有限的字母表查找下一个数字。 我们可以通过从最低有效位置扫描到最高有效位置来修复无效数字，每当遇到 2 时，我们都会递增下一个位置并将下面的所有内容归零。 这类似于二进制“没有连续数字的下一个数字”，但适用于带有禁止数字的基数 3。 

一旦我们强制所有数字都是 0 或 1，我们仍然可能会得到下面的结果$n$，因此我们通过控制进位传播构造严格大于或等于原始数字的最小有效配置来确保最小性。
