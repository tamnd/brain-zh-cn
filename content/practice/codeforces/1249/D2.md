 ## 解决方案
 ## 问题理解

 我们在数轴上得到了一组整数线段。 每个线段覆盖其端点之间的每个整数点。 如果一个点被超过多个覆盖，那么它就会成为问题$k$同时进行分段。 我们的任务是删除尽可能少的段，以便不覆盖任何整数点。 

重新解释这一点的一个有用方法是想象一个时间线，其中每个部分都是一个活动间隔。 在任何整数坐标处，我们计算有多少个活动间隔与其重叠。 我们可以删除间隔，并且我们希望任何地方的最终最大重叠最多为$k$。 

约束条件很大，最多可达$2 \cdot 10^5$段和坐标值达到相同的范围。 这排除了任何对每个段或每个点重复重新计算重叠计数的方法。 任何试图在每次删除时天真地模拟覆盖范围的东西都会降级为$O(n^2)$，这太慢了。 解决方案必须围绕$O(n \log n)$或者$O(n)$。 

一个微妙的问题是坏点并不是孤立的。 如果在某个坐标处重叠超过$k$，那么可能有多个段负责，并且尽早删除错误的段可能会导致未来不必要的删除。 另一种故障模式是贪婪地删除最短或最早的段，而不考虑过载实际发生在哪里。 

例如，假设许多长线段与单个小区域重叠，并且短线段也穿过该区域。 首先删除短段对于解决过载没有任何帮助，并且浪费了删除操作。 

正确的策略必须关注_重叠超出的地方$k$_ 并删除在这些点上贡献最大的片段。 

## 方法

 一种强力的想法是重复计算所有点的最大重叠并删除参与某些过载点的一个段。 每次重叠的重新计算是$O(n \cdot R)$或者充其量$O(n \log R)$进行扫描，直到$n$次导致大约$O(n^2)$行为。 和$2 \cdot 10^5$段，这是不可行的。 

关键的观察是，我们不需要在每次删除后进行完整的全局重新计算。 相反，我们可以按右端点递增的顺序处理线段，同时维护覆盖每个点的当前活动线段集。 当我们达到一个点，超过$k$段重叠，我们应该删除当前活动的段中向右延伸最远的段之一。 

这个选择至关重要。 如果某个段较早结束，则删除它只会减少本地覆盖范围。 延伸到遥远未来的部分继续在许多后续点造成潜在的过载。 通过删除具有最大右端点的线段，我们可以最大限度地减少未来的干扰，同时修复当前的违规问题。 

我们模拟位置上的扫描线，维护按右端点排序的活动段的最大结构。 当覆盖范围超过$k$，我们删除具有最大右端点的线段并将其标记为已删除。 这确保了每一次违规行为都能以最小的未来成本得到解决。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2 \log n)$|$O(n)$| 太慢了 |
 | 最佳扫描+堆|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们处理扫描线上位置上的所有线段端点。 

1. 按段的左端点对段进行排序。 当我们从左向右移动时，我们将激活分段。 
2.维护一个活动段的优先级队列（最大堆），以右端点为键，这样我们就可以快速找到向右延伸最远的段。 
3. 在已排序的段上维护一个指针，以激活左端点 ≤ 当前位置的所有段。 
4. 从左向右扫坐标线。 在每个位置：

 我们将所有新开始的段插入堆中。 
5. 如果堆包含超过$k$活动段，我们必须解决这个位置的过载问题。 我们贪婪地删除段：

 我们重复提取具有最大右端点的段并将其标记为已删除，直到活动大小最多为$k$。 

我们删除最远末端部分的原因是，它会导致当前的过载，并将继续对未来的位置做出贡献，因此保留它是最“昂贵”的。 
6. 继续，直到处理完所有段。 
7. 输出所有删除的段索引。 

### 为什么它有效

 在任意坐标，如果超过$k$部分覆盖它，至少其中一个必须被移除。 在所有活动段中，删除具有最大右端点的段是最佳选择，因为它消除了最长剩余间隔的覆盖范围。 任何替代的去除要么无法解决当前的过载，要么导致未来相同或更高的过载。 这种贪婪的选择确保一旦删除某个段，就永远不需要重新考虑它，并且未来的步骤不会变得比必要的更糟糕。 

不变的是，在处理每个坐标之后，直到该坐标的点都不会被超过$k$未删除的段，并且在解决过去过载的所有有效方法中，该算法为未来的段保留了最大可能的灵活性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, k = map(int, input().split())
    segs = []
    for i in range(n):
        l, r = map(int, input().split())
        segs.append((l, r, i + 1))

    segs.sort()
    
    active = []  # max heap by r (store (-r, id))
    removed = [False] * (n + 1)
    
    j = 0
    for i in range(1, 200001):
        while j < n and segs[j][0] == i:
            l, r, idx = segs[j]
            heapq.heappush(active, (-r, idx))
            j += 1
        
        # clean removed segments from heap lazily
        while active and removed[active[0][1]]:
            heapq.heappop(active)
        
        while len(active) > k:
            r_neg, idx = heapq.heappop(active)
            removed[idx] = True

    ans = [i for i in range(1, n + 1) if removed[i]]
    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```该代码对段进行排序并扫描所有整数坐标。 每次一个段开始时，它都会被添加到由其右端点键控的最大堆中。 堆始终代表当前活动的段。 

当活动段数超过$k$，我们删除具有最大右端点的端点，因为它对未来的覆盖范围贡献最大。 这`removed`数组确保我们可以跟踪删除，而无需从所有结构中物理删除元素。 

一个微妙的点是我们迭代所有坐标直到$2 \cdot 10^5$。 这是安全的，因为坐标范围是有界的，并且它保证我们按顺序捕获每个段激活事件。

 | 5 | 4,8 | 删除 8 | 第五 |

 ## 边缘情况

 一种重要的边缘情况是所有段都相同。 例如：```
3 1
1 5
1 5
1 5
```在位置 1，所有三个段都处于活动状态，因此我们必须删除两个。 堆总是删除具有最大右端点的段，但所有段都是相同的，因此任何两个都是有效的。 该算法正确地输出了两个移除结果。 

另一个边缘情况是嵌套段，例如：```
4 2
1 10
2 9
3 8
4 7
```在峰值重叠时，所有四个段都处于活动状态。 自从$k=2$，必须删除两个。 堆首先删除最外层的段，这是正确的，因为它们在最宽的范围内主导覆盖范围。 

最后的边缘情况是稀疏激活，其中重叠仅短暂超过$k$。 扫描可确保即使是短暂的违规行为也能在其发生的坐标处准确捕获，从而防止去除不足，否则会留下隐藏的坏点。
