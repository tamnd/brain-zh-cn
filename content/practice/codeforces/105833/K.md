 ## 解决方案
 ## 问题理解

 该问题可以视为图探索问题，其中每条边都是一条具有相关成本的火车线路，但成本不会立即支付。 相反，雷德在旅行时获得了边缘的“许可证”，并且只有当他最终离开车站时$N$，支付系统激活一个特殊规则：只有$K$最便宜的购买许可证实际上需要付费，而所有其他许可证实际上都是免费的。 

我们得到一个无向图，最多可达$10^5$节点和$2 \cdot 10^5$边缘。 每条边连接两个站并有成本。 红色从节点 1 开始并且必须到达节点$N$。 在旅行时，每当他到达边缘的端点时，他就可以购买该边缘的许可证，之后该边缘就可以用于双向免费旅行。 关键在于，总成本不是所有购买边的总和，而是$K$最小的购买边缘成本。 

因此，决定的不仅仅是采取哪条路径，而是在探索过程中故意“收集”哪些边，以便最终购买的边的多重集具有便宜的价格。$K$-子集。 

这些约束意味着任何解决方案在边数上都必须接近线性或近线性，因为$M$可以是$2 \cdot 10^5$。 使用堆的最短路径风格方法是可以接受的，但是任何重复排序或枚举所有子集的方法都是立即不可能的。 对遍历和购买边的所有可能方式进行天真的指数探索是不可能的，因为每一步都会在邻接列表和潜在的边购买决策上分支，从而导致指数增长。 

一个微妙的一点是，多次访问一个节点很重要，因为它允许购买在不同时刻发生的边。 粗心的最短路径解释会假设边只能沿单个路径使用，但在这里购买边后回溯的能力会显着改变结构。 

第二个不明显的问题是到达节点并不等同于“完成”。 红色到达后可以继续行驶$N$，所以暂时超出的路径$N$或重新访问区域如果有助于收集更好的边缘，则它们是有效的。 

第三个陷阱是假设我们只关心从 1 到 1 的单个简单路径上的边$N$。 这是错误的，因为购买边缘允许遍历独立于其在最终路线中的角色。 

## 方法

 蛮力的想法是模拟从节点 1 走到节点的所有可能方式$N$，并在每一步决定是否购买当前优势。 在步行过程中，我们维护购买的边集，当我们第一次到达时$N$，我们计算总和$K$该集合中最小的边成本。 这是正确的，但立即爆炸：即使我们将步行长度限制为$O(N)$，每一步分支成多个边，并且可能的购买子集的数量呈指数增长$M$。 即使忽略路径选择，评估每次遍历的最佳子集也需要排序$M$值反复。 

关键的结构观察是，关于遍历的唯一重要的是最终购买哪些边，而不是确切的顺序。 遍历本身仅充当可行性条件：如果在某个时刻我们到达其端点之一，则可以购买一条边。 所以真正的问题变成了：从这个意义上讲，哪些边的子集是从节点 1“可达”的，以及在这些可达子集中，我们如何最小化边的总和$K$最小的成本。 

这将问题转化为类似最短路径的扩展，其中状态是节点，但转换取决于收集解锁更多移动的边。 我们不考虑路径，而是将其视为逐步发现可到达边缘的连接区域，同时保持尽力而为的成本结构来跟踪$K$迄今为止看到的最便宜的边缘。 

编码的标准方式“我们只关心$K$最小元素”是维持最大大小的最大堆$K$，所以我们总是保留最便宜的$K$在可达区域中遇到的边缘。 遍历变成了图探索，每次到达新节点时，我们都会暴露其关联边，并且任何新边都可能进一步扩展可达性。 

这导致了节点上类似 Dijkstra 的过程，但有一个额外的结构来保持最佳状态$K$到目前为止收集的边缘成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对路径和子集的暴力破解 | 指数| 指数| 太慢了|
 | 可达性 + Dijkstra + top-K 堆 |$O((N+M)\log N + M \log K)$|$O(N+M)$| 已接受 |

 ## 算法演练

 我们将该过程建模为从节点 1 开始的图遍历，逐步发现可到达的节点并同时收集可用的边。 

1、初始化一个优先级队列，从节点1开始进行图遍历，并将节点1标记为可达。 
2. 维护一个存储最小的结构$K$到目前为止看到的边缘成本。 最大堆大小$K$使用这样当新的边成本到达时，我们将其插入，并且如果大小超过$K$，我们删除最大的元素。 这确保我们始终保留$K$所有收集的边中成本最小。 
3. 探索节点时$u$，迭代所有与$u$。 对于每条边$(u, v, c)$，我们尝试通过增加成本来“发现”它$c$进入顶部-$K$结构。 这是有效的原因是一旦我们可以达到$u$，我们可以购买该优势。 
4. 如果另一个端点$v$尚未被访问过，我们将其标记为可达，并将其添加到遍历队列中。 此步骤通过新的可用边传播可达性。 
5. 继续，直到无法到达新节点。 到那时，我们已经按照“到达端点时边变得可用”的规则，用尽了从节点 1 开始可以遇到的所有边。 
6. 将最终答案计算为当前存储在中的值的总和$K$-堆。 这些代表了$K$可到达子图中最便宜的可购买边。 

### 为什么它有效

 核心不变量是，在任何时刻，访问的节点正是使用已发现的边从节点 1 可达的节点。 每次节点变得可达时，其所有关联边都符合购买资格，因此不会跳过任何可能购买的边。 堆不变量确保在所有符合条件的边中，我们只保留最小的边$K$，并且由于最终付款忽略了除$K$最便宜的购买边缘，尽早丢弃较大的边缘永远不会改变最终的总和。 遍历保证如果一条边可能影响可达性，则其端点最终将被处理，因此不会错过任何有效的贡献边。 

## Python 解决方案```python
import sys
import heapq
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        x, y, c = map(int, input().split())
        g[x].append((y, c))
        g[y].append((x, c))

    visited = [False] * (n + 1)
    visited[1] = True

    pq_nodes = [1]

    # max heap via negation for keeping k smallest edges
    best = []

    while pq_nodes:
        u = pq_nodes.pop()

        for v, c in g[u]:
            if len(best) < k:
                heapq.heappush(best, -c)
            else:
                if -best[0] > c:
                    heapq.heapreplace(best, -c)

            if not visited[v]:
                visited[v] = True
                pq_nodes.append(v)

    print(-sum(best))

if __name__ == "__main__":
    solve()
```该图存储为邻接列表，因为当节点变得可访问时，我们必须重复公开边。 这`visited`array 确保每个节点都被处理一次，从而防止重复扩展循环。 

这`best`堆存储负值，以便当前保留的候选值中最大的始终位于顶部。 这使得当出现更好（更小的）边缘时很容易丢弃它。 尺寸限制为$K$至关重要，因为如果没有它，我们将存储所有边缘并失去效率优势。 

节点处理堆栈`pq_nodes`可以用队列或优先级结构来代替，但在这个问题中任何遍历顺序都足够了，因为所有可达节点最终都会暴露它们的边缘，并且节点扩展没有距离约束。

 ## 边缘情况

 一个关键的边缘情况是当$K$超过从节点 1 可到达的边数。在这种情况下，算法永远不会将堆填充到指定大小$K$，最终的总和自然包括所有收集到的边。 例如，在线性链中$1-2-3-4$和$K=10$，每条边都包含在堆中，总和就是总路径成本。 

另一个微妙的情况是相同节点之间有多个平行边。 在遍历过程中，每条边都是独立处理的，因此即使两条边连接同一对节点，也会单独考虑将它们包含在堆中。 这是至关重要的，因为较便宜的可能是最佳选择的一部分$K$-放。 

最后一个重要的情况是当探索到达节点时$N$早期的。 算法不会停止在节点$N$因为它之外的其他节点可能仍然是可达的，并且可能会暴露更便宜的边缘。 提前终止会错误地错过这些贡献，因此遍历必须继续，直到实现可达空间的关闭。
