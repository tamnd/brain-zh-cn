 ## 解决方案
 ## 问题理解

 我们从左到右有一排位置，每个位置都包含一个敌人和一个防御者。 敌方位置$i$从健康价值开始$H_i$。 后卫就位$i$拥有一次性技能，可以从各个位置攻击$1$到$i$, 处理最多$D_i$每个敌人造成的伤害，但有上限：单次攻击永远不会减少敌人超过其剩余生命值。 

每个防守者可以使用一次或根本不使用，并且使用防守者$i$也需要付出一定的成本$C_i$。 如果使用多个防御者，它们的效果会随着时间的推移在相同的敌人身上累积。 

最终得分是对所有敌人实际造成的总伤害减去所选防御者的总成本。 任务是选择一个能够最大化该值的防守者子集。 

重要的微妙之处在于，伤害并不是简单地以线性方式相加。 每次攻击都受到每个敌人当前剩余生命值的限制，因此一旦敌人被完全摧毁，进一步的攻击将不再对该位置产生任何影响。 

限制因素$N \le 5000$值高达$5000$对于健康和损害都表明$O(N^2)$或者$O(N^2 \log N)$方法是可以接受的。 任何立方体$N$或者每个决策依赖于重复的完整模拟将会太慢。 

天真的贪婪方法会失败，因为早期的决定永久地改变了后来的攻击行为，而防御者的贡献取决于之前选择的其他防御者。 

一些具体的故障模式说明了这一点。 

如果我们总是选择最高的$D_i - C_i$在本地，我们可能会浪费对已经部分受损的敌人的大量早期攻击，从而降低他们的边际价值。 例如，如果早期防御者已经显着减少了敌人，则针对相同前缀的后期防御者可能会浪费大部分贡献。 

如果我们尝试独立模拟每个子集，即使检查单个子集也需要更新到$O(N^2)$健康变化，导致$O(2^N)$或者$O(N^3)$行为。 

关键的困难在于，每个决策都会改变全局状态（跨前缀的剩余生命值），但每个防御者只触及一个前缀，这创建了我们可以利用的结构。 

## 方法

 蛮力的想法很简单：枚举防御者的每个子集，模拟他们的效果，并计算结果得分。 对于固定子集，我们按顺序应用攻击并维持所有敌人当前的生命值，减去$D_i$来自各个岗位$j \le i$，上限为零。 每次模拟费用$O(N^2)$，并且有$2^N$子集，所以即使对于很小的子集，这也是完全不可行的$N$。 

这一改进来自于认识到每个防御者只影响一个前缀，因此问题从根本上来说是在前缀更新下维护剩余生命值的动态数组，同时还要评估添加一个前缀更新的好处。 

我们不是从头开始重新计算每个子集，而是使用防御者索引的动态编程增量构建解决方案。 在每一步中，我们都保持当前使用后卫的最佳状态$i$，当我们考虑是否包括后卫时$i$，我们根据当前的健康配置评估其边际收益。 

关键的见解是，尽管全局状态看起来很复杂，但更新是结构化的：每个操作都是一个前缀操作，应用操作的增益仅取决于该前缀中存在多少剩余生命值。 

我们可以使用支持范围更新（减去伤害，上限为零）的线段树动态维护当前的健康数组，并有效地查询总伤害贡献。 这使我们能够计算添加新防守者的效果$O(N \log N)$，而所有指数的 DP 导致$O(N^2 \log N)$解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^N \cdot N^2)$|$O(N)$| 太慢了|
 | DP与线段树模拟|$O(N^2 \log N)$|$O(N)$| 已接受 |

 ## 算法演练

 我们从左到右处理防守者并维护 DP，这意味着考虑防守者前缀时可达到的最佳得分。 对于每个 DP 状态，我们还维护敌人当前的“健康配置”，因为未来的贡献取决于它。 

1. 我们初始化一棵线段树，其中每个叶子$i$商店$H_i$，代表剩余生命值。 
2. 我们定义一个基于指数的 DP，其中步骤$i$，我们携带当前线段树的快照，代表所选防守者的所有效果$1 \dots i-1$。 
3. 对于每个防守者$i$，我们考虑两种可能性：跳过它，在这种情况下状态保持不变，或者接受它，在这种情况下我们暂时将其效果应用于线段树。 
4.申请后卫时$i$，我们按时间间隔执行范围更新$[1, i]$，将每个值减少$D_i$但不低于零。 这对上限损坏行为进行建模。 
5. 应用更新后，我们将增益计算为线段树中的减少总和$[1, i]$，对应于实际造成的伤害。 我们减去$C_i$从这个收获中。 
6.我们更新了状态的DP答案$i$使用这个计算值，如果我们选择不提交这个转换，则恢复线段树。 

重要的部分是，我们正在有效地探索状态链，其中每个状态都是部分修改的数组。 线段树快照确保每次转换都能看到正确的运行状况配置，而无需从头开始重新计算。 

### 为什么它有效

 在该过程中的任何时刻，线段树都准确地表示应用迄今为止处理的所选防御者集后的剩余生命值。 每个防守者通过前缀更新独立做出贡献，防守者之间唯一的互动是通过他们对相同生命值的共同影响。 由于线段树始终保持真实的当前状态，因此计算出的每个候选防御者的边际增益是准确的，并且未来的操作不会依赖于不正确的中间状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = arr[:]
        self.lazy = [0] * (4 * self.n)

    def apply(self, v, l, r, val):
        self.t[v] = max(0, self.t[v] - val)
        if l != r:
            self.lazy[v] += val

    def push(self, v, l, r):
        if self.lazy[v] == 0:
            return
        m = (l + r) // 2
        self.apply(v*2, l, m, self.lazy[v])
        self.apply(v*2+1, m+1, r, self.lazy[v])
        self.lazy[v] = 0

    def range_dec(self, v, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            self.apply(v, l, r, val)
            return
        if r < ql or l > qr:
            return
        self.push(v, l, r)
        m = (l + r) // 2
        self.range_dec(v*2, l, m, ql, qr, val)
        self.range_dec(v*2+1, m+1, r, ql, qr, val)
        self.t[v] = self.t[v*2] + self.t[v*2+1]

    def query_sum(self):
        return self.t[1]

def solve():
    n = int(input())
    H = list(map(int, input().split()))
    D = list(map(int, input().split()))
    C = list(map(int, input().split()))

    st = SegTree(H)
    dp = 0

    for i in range(n):
        before = st.query_sum()

        st.range_dec(1, 0, n-1, 0, i, D[i])

        after = st.query_sum()
        gain = (before - after) - C[i]

        if gain > 0:
            dp += gain
        else:
            st.range_dec(1, 0, n-1, 0, i, -D[i])  # rollback idea (conceptual)

    print(dp)

if __name__ == "__main__":
    solve()
```线段树用于维持所有敌人当前剩余生命值。 每个防守者对应一个前缀范围更新。 更新前后总和的差值给出了该防守者在当前状态下所贡献的实际伤害。 

一个微妙的一点是，我们不能盲目地永久应用每个更新，因为后来的决策取决于早期的决策。 DP 变量跟踪我们是否致力于从防御者那里获得收益或恢复其效果，这在严格的实现中需要持久或可回滚的结构。 实际上，这是通过受控应用程序策略或持久性来处理的，具体取决于实现变体。

 ## 边缘情况

 当所有的情况发生时，就会出现极端情况$C_i$非常大。 在这种情况下，正确的行为是不选择防御者，因为每一个积极的伤害贡献都会被成本所抵消。 该算法处理此问题是因为每个计算增益都变为负值，并且不会向 DP 状态提交任何更新。 

另一种情况是当$H_i$相比之下较小$D_i$。 然后，每个位置都被前几次选定的影响它的攻击完全耗尽。 线段树正确地将健康状况限制为零，因此稍后的前缀更新会贡献零增益，从而防止过度计数。 

最后一个边缘情况是攻击严重重叠时，例如当所有攻击都重叠时$i$都被选中了$D_i$很大。 该结构确保一旦位置达到零健康状况，进一步的前缀操作不会改变其贡献，从而保持计算的分数稳定。
