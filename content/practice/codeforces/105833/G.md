 ## 解决方案
 ## 问题理解

 我们得到一个有向图，其中每个顶点都有到一组邻居的传出边。 令牌从选定的顶点开始，两名玩家轮流沿着边缘移动令牌，同时累积分数。 每次移动令牌，分数就会增加一，但如何选择下一个顶点的规则取决于当前顶点的出度。 

如果顶点没有出边，则游戏立即结束。 如果它恰好有一个出边，则强制移动。 如果它至少有两个传出边缘，则当前玩家选择两个不同的传出邻居，然后对手选择这两个中的哪一个成为下一个位置。 

我们被要求计算，对于每个起始顶点，第一个玩家在双方最佳游戏下可以保证的最大移动次数。 如果可以强制游戏无限期地继续，则该起始顶点的答案为 -1。 

该图最多可以有 200,000 个顶点和 400,000 个边。 任何单独检查每个起始顶点的过渡的解决方案都会太慢。 即使每个节点的线性扫描也会导致二次行为，这在一秒约束下是不可能的。 这促使我们走向图上的全局结构而不是独立的模拟。 

有些情况很容易处理错误。 

如果一个顶点是有向循环的一部分，其中每个顶点的出度至少为 1，并且玩家可以永远避免终止，则答案必须为 -1。 假设最终终止的朴素最短路径或 DP 将错误地分配有限值。 

如果顶点的出度为 1 并指向循环，则移动的强制性质意味着循环属性向后传播。 忽略强制链会导致游戏长度的错误截断。 

当一个顶点有两条传出边，并且两条传出边最终达到相同状态时，就会出现另一种微妙的情况。 天真的贪婪假设“两个选择意味着分支”可能会高估第一个玩家的控制力，因为对手实际上将其减少为单个可到达的延续。 

## 方法

 暴力方法从每个起始顶点模拟游戏，并探索两个玩家之间所有可能的交互。 在每个分支顶点，我们尝试所有对的传出边并模拟对手的最佳响应。 这很快就会变成指数，因为每个分支节点都会在图中引入一个最小-最大决策树。 即使记忆也没有多大帮助，因为状态不仅仅是顶点，还取决于在最佳对抗性游戏下每个顶点被访问的次数。 

关键的观察是游戏不依赖于当前顶点之外的历史。 每个顶点都可以分配一个值：起始玩家从该点开始仍然可以保证的最大步数，如果游戏可以永远延长，则为无穷大。 

这将问题转化为具有两种转换的图 DP。 如果一个顶点恰好有一条出边，则该值是其后继边的值加一。 如果它有多个出边，则当前玩家有效地选择两个候选者，并且对手强制其中最小结果。 这相当于说一个节点的价值取决于选择两个后继者并采取两个结果中最坏的一个，而玩家则试图最大化这个最坏情况的结果。 

这种结构自然会导致以类似于多源传播的方式反转图并计算值，其中没有传出边的顶点充当值为零的终端状态。 传播以逆拓扑顺序进行，但循环需要特殊处理：任何无需强制终止即可到达的循环都会形成无限循环状态。

该解决方案简化为识别哪些顶点可以到达“最佳播放下的非终止强连接区域”，否则计算最长的向后强制路径。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 指数| O(N + M) | 太慢了|
 | 具有反向传播的图 DP | O(N + M) | O(N + M) | 已接受 |

 ## 算法演练

 1. 构建邻接表并计算每个顶点的出度。 

这是必需的，因为转换规则完全取决于次数是 0、1 还是至少 2。 
2. 初始化一个队列，其中包含出度为 0 的所有顶点，并为它们分配值 0。 

这些是终止状态，因为游戏在进入时立即结束。 
3. 使用队列以相反方式处理顶点，为每个顶点维护最佳已知答案以及已解决的传出转换数量。 

这个想法是，一旦一个顶点的所有选择都“从其子节点的角度进行了评估”，该顶点就变得可解。 
4. 对于只有一条出边的顶点，直接将值作为后继值加一进行传播。 

这是被迫的移动，因此不存在任何战略选择。 
5. 对于至少具有两条出边的顶点，跟踪最好的两个后继值。 

由于对手在所选的两个结果中选择了最差的结果，因此有效值由当前玩家可以提供的最佳对决定，从而最大限度地减少对手避免长路径的能力。 
6. 检测传播后的循环或未解析的顶点。 

处理后仍具有未定义值的任何顶点都是结构的一部分或导致游戏可以无限期延长的结构，因此分配 -1。 

### 为什么它有效

 关键的不变量是，一旦顶点的值固定，它就代表在最佳游戏下从该顶点出发的最大保证步数。 根据定义，终端顶点是正确的。 强制顶点向后传播正确性，因为不涉及任何决策。 对于分支顶点，最小-最大结构分解为选择一对最坏结果最大化的传出边，并且一旦知道所有后继值，就完全确定了这一点。 由于值仅以依赖关系的相反顺序依赖于已处理的状态，因此以后的更新不会使计算值无效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import deque

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    indeg = [0] * n
    outdeg = [0] * n

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        outdeg[u] += 1
        indeg[v] += 1

    # dp[i] = best guaranteed score from i, -1 means infinite
    dp = [None] * n
    q = deque()

    for i in range(n):
        if outdeg[i] == 0:
            dp[i] = 0
            q.append(i)

    # reverse graph
    rg = [[] for _ in range(n)]
    for u in range(n):
        for v in g[u]:
            rg[v].append(u)

    remaining = outdeg[:]

    while q:
        v = q.popleft()
        for u in rg[v]:
            if dp[u] is not None:
                continue

            remaining[u] -= 1

            if outdeg[u] == 1:
                # forced transition
                dp[u] = dp[v] + 1
                q.append(u)
            else:
                # collect computed neighbors
                vals = []
                for to in g[u]:
                    if dp[to] is not None:
                        vals.append(dp[to])

                if len(vals) >= 2:
                    vals.sort(reverse=True)
                    dp[u] = vals[1] + 1
                    q.append(u)

    for i in range(n):
        if dp[i] is None:
            dp[i] = -1

    print(*dp)

if __name__ == "__main__":
    solve()
```实现遵循反向传播思想。 我们首先初始化终端节点，然后沿着反向边缘向后推值。 对于具有单个出边的节点，转换是确定性的，因此我们立即确定它们的值。 对于分支节点，我们等到看到足够的后继信息来确定最佳结果对。 

一个常见的实现错误是尝试直接按拓扑顺序计算值而不处理循环，这会导致无限循环或不正确的有限答案。 另一个微妙的问题是在评估分支节点时将“可用边缘”与“已处理边缘”混合在一起； 只有最终确定的后继值才应有所贡献。

 ## 边缘情况

 纯循环例如`1 → 2 → 3 → 1`永远不会到达终端节点，因此在反向传播期间无法最终确定 DP 值。 该算法使所有节点未定义，并在最后正确地将它们转换为 -1，代表无限的游戏玩法。 

终止于水槽的线性链，例如`1 → 2 → 3 → 4`其中 4 没有传出边缘，确定性地向后传播值。 每个节点恰好收到一个强制后继者，并且分数清晰地累积，没有歧义。 

两个传出边都通向同一后继节点的分支节点仍然可以正确运行，因为算法会收集最终值，并且重复路径不会人为地增加最优选择集。
