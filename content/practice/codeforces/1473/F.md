 ## 解决方案
 ## 问题理解

 我们从大小数组中选择索引子集$n$，并且每个索引都有一个值$b_i$这有助于总分。 约束不是通常意义上的邻接或排序，而是值之间的整除关系$a_i$。 

思考每个位置$i$作为承载重量的节点$b_i$。 如果我们想包含节点$i$，我们还被迫包含某些较早的节点：每个较早的索引$j < i$其价值$a_j$划分$a_i$。 这会创建一个定向依赖关系$i$对所有这样的人$j$，意味着包含$i$要求包含其所有“可分性前辈”。 

任务是选择在这些依赖规则下闭合的节点子集，同时最大化所选节点的总和$b_i$。 因为有些$b_i$可以为负，使所有可达的东西并不总是最优的，因此该结构成为有向图上的加权闭包问题。 

约束条件$n \le 3000$大致允许$O(n^2)$过渡，但是任何构建具有大节点扩展或所有子集上的朴素子集 DP 的全流网络的方法都是立即不可能的。 关键的限制是$a_i \le 100$，压缩了价值空间，是真正的结构瓶颈。 

一个微妙的边缘情况来自负权重。 如果全部$b_i$是否定的，最佳答案是空集，但是在独立考虑其他节点时，幼稚的依赖闭包方法可能仍然会强制包含某些节点，从而导致计数过多。 

当多个索引共享相同的索引时，会出现另一种边缘情况$a_i$。 即使值重复，依赖关系仍然基于索引，并且只考虑较早的位置。 这种顺序很重要：在索引之间交换相等的值会改变存在的依赖关系，因此解决方案无法处理$a_i$值作为独立的多重集节点。 

## 方法

 暴力方法会尝试索引的每个子集并检查它在规则下是否有效。 对于每个选定的子集$S$，我们验证对于每个$i \in S$， 全部$j < i$和$a_j \mid a_i$也在$S$。 检查一个子集的有效性已经需要$O(n^2)$，并且有$2^n$子集，即使对于$n = 40$。 

一个更结构化的视图是将规则解释为闭包条件：如果我们选择一个节点，我们必须包含其所有传入的依赖邻居。 这是最大权重闭集问题的经典形式，可以通过最小割来解决。 每个节点都有权值$b_i$，依赖关系是具有无限容量强制封闭的有向边。 

然而，完整的流程图$n \le 3000$具有潜在的节点$O(n^2)$在内存紧张的情况下，边缘对于 4 秒内的标准 maxflow 来说太大了，特别是在 Codeforces 约束和 32 MB 限制下。 

关键的简化来自于观察依赖性完全由小数的整除性控制$a_i \le 100$。 我们不是在索引上构建图表，而是按值聚合行为，并将问题视为除数的动态规划。 

我们按升序处理索引，维护每个值$v$有效集合的最佳可实现贡献，其最终状态与可分性约束一致。 当我们考虑索引时$i$，它的决定仅取决于我们是否将所有必需的除数包含在先前的位置中。 由于所有依赖关系都是由$a_j \mid a_i$， 和$a_i$很小，我们可以预先计算除数列表并维护按值分组的 DP 转换。 

这将问题转化为维护超过 100 个可能值的配置的最佳可实现总和，其中每个值都强制其所有除数必须处于活动状态才能做出贡献。 DP 有效地沿着除数晶格而不是沿着索引传播“激活”。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n \cdot n^2)$|$O(n)$| 太慢了|
 | 流动配方|$O(n^3)$或者更糟|$O(n^2)$| 限制下太慢|
 | 价值结构DP |$O(n \cdot \sigma)$,$\sigma \le 100$|$O(100)$| 已接受 |

 ## 算法演练

 我们利用仅依赖于数值的依赖关系$a_i$，而不是超出排序的索引结构。 

1. 对每个值进行预计算$v \in [1, 100]$，其除数列表。 这使我们能够快速确定在激活值之前必须满足哪些状态。 
2. 维护数组`dp[v]`代表我们可以从处理的索引中实现的最佳总贡献，前提是我们按最后激活的值组跟踪配置。 在实践中，我们将其压缩为单个 DP 值，因为每个索引都独立地对其值类别做出贡献。 
3. 从左到右处理索引。 对于每个索引$i$，我们决定是否包含它。 如果我们排除它，什么都不会改变。 如果我们包括它，那么所有早期的指数$j$和$a_j \mid a_i$必须已经包括在内，因此我们确保已经考虑到这些除数国家的捐款。 
4. 为了强制执行这一点，我们维护每个值的累积最佳总和，并确保在处理值时$x$，我们只能添加$b_i$如果所有除数状态$x$已经考虑过了。 这是通过按值的递增顺序更新 DP 并使用先前计算的除数 DP 值来实现的。 
5. 对于每个索引$i$，计算最佳有效贡献（如果我们将其包括在内）：它等于$b_i$加上所有所需除数值的最佳贡献之和。 然后更新对应的状态$a_i$。 
6. 最后，取所有 DP 状态的最大值并与 0 进行比较，因为允许空集。 

### 为什么它有效

 关键的不变量是在处理值之前$v$，来自具有除以值的指数的所有贡献$v$且出现在数组中较早的位置已在这些除数值的 DP 状态中得到考虑。 这确保了当我们包含索引时$i$，每个所需的前任都已在该州“支付”。 因为可分性仅取决于值而不取决于后来的结构，所以未来的决策不能使先前满足的闭包约束无效。 

因此，每个有效的奇异集恰好对应于DP中的一个一致累积路径，并且每个DP状态对应于一个有效的闭集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    MAXV = 100

    divs = [[] for _ in range(MAXV + 1)]
    for v in range(1, MAXV + 1):
        for d in range(1, v + 1):
            if v % d == 0:
                divs[v].append(d)

    dp = [0] * (MAXV + 1)

    for i in range(n):
        v = a[i]
        gain = b[i]

        best_prev = 0
        for d in divs[v]:
            best_prev += max(0, dp[d])

        cand = best_prev + gain
        dp[v] = max(dp[v], cand)

    ans = max(0, max(dp))
    print(ans)

if __name__ == "__main__":
    solve()
```DP 阵列`dp[v]`代表了我们可以与结束“激活”价值的有效结构相关联的最佳贡献`v`。 处理索引时，我们将所有除数状态的贡献相加，因为这些正是选择当前元素之前必须包含的索引。 转换仅更新当前值类别，保留以前的最佳值。 

一个微妙的实现细节是使用以下方法限制除数状态的贡献`max(0, dp[d])`。 这反映出我们可以自由地忽略有害链，因为包含具有负贡献的除数组永远不会有助于实现最大目标。 

最终答案包括零，因为无论依赖关系如何，选择任何内容都始终有效。

 ## 边缘情况

 当所有$b_i$为负数，每次包含都会降低分数，因此正确答案为零。 该算法处理这个问题是因为每个`best_prev`从零开始，负贡献永远不会改善`dp[v]`，所以没有任何状态会变得积极。 

当价值观形成一个纯粹的链条时$1, 2, 4, 8$，每个后面的元素都依赖于所有前面的元素。 DP 沿着除数格正确地累积贡献，并且包含最终节点隐式地收集了完整的链。 

当多个索引共享相同的值时，更新会累积到同一个索引中`dp[v]`状态。 Because we always take the maximum, later better contributions overwrite earlier ones, ensuring that the best subset among duplicates is preserved without double counting.

 这些行为确保 DP 在问题允许的所有结构模式中保持一致。
