 ## 解决方案
 ## 问题理解

 我们得到两个数字多重集，每个数字只有 0、1 或 2。两个多重集的大小相同，因为我们被告知每个序列匹配中的总计数。 我们可以任意重新排序两个序列，然后我们将元素逐个位置配对。 

每对贡献一个值，该值取决于两个所选数字的相对顺序。 如果第一个序列的数字较大，则贡献为正并且等于乘积。 如果它们相等，则贡献为零。 如果它更小，则贡献为负，同样基于产品。 

任务是排列两个序列，以使所有对的总和最大化。 

计数的约束可以大到 10^8，而测试用例的数量最多可以达到 10^4，立即排除任何每个元素的模拟。 我们无法显式构造数组或进行匹配。 一切都必须纯粹由计数来决定。 

一种常见的失败模式来自于将其视为通用排序和匹配问题，而不利用值只有 0、1 和 2 的事实。例如，人们可能会尝试贪婪地匹配最大与最大，但评分是不对称的并且取决于方向，因此幼稚的排序逻辑可能会放错 0 和 2，并失去避免负面贡献的潜在收益。 

平衡 0 时会出现一个具体的陷阱。 配对 0 来自`a`与 2 从`b`是强烈的负数，但将其与 1 或 0 配对的危害要小得多。 忽略这些不对称惩罚的幼稚策略将始终多计损失。 

## 方法

 蛮力的想法很简单：扩展两个序列，尝试所有配对排列，并计算最佳总和。 这是正确的，因为它会在重新排序后探索所有可能的匹配。 然而，每个序列可能非常大，最多可达 10^8 个元素，因此即使存储数组也是不可能的，更不用说对它们进行排列了。 即使我们忽略记忆，排列的阶乘增长也会使这种方法变得不可想象。 

关键的见解是只有频率才重要，并且相互作用完全由配对类型决定。 由于值来自一个微小的固定集合 {0,1,2}，因此我们可以考虑选择多少个 0-0、0-1、0-2、1-2 等对。 

我们希望最大限度地发挥积极贡献并避免消极贡献。 遵守评分规则：

 - 2 个节拍 1 和 0（当 2 处于正值时为正）`a`，反转时为负）
 - 1 击败 0 但输给 2
 - 0总是弱

 因此，最优的策略就是以高价值元素优先的方式进行贪婪匹配，同时防止低价值元素被迫输掉与高价值对手的对决。 

这成为一个经典的贪婪配对问题：始终尝试首先匹配最佳有益配对，然后继续进行下一个最佳可用交互，仔细跟踪剩余计数。 

我们仅使用计数来模拟这一点，按优先级顺序重复匹配类别：

 首先使用 2 在`a`反对 1 中`b`，然后 2 对 0，然后 1 对 0，等等，总是消耗尽可能多的。 

这种结构化匹配确保每次我们获得正收益时，我们都不会牺牲更大的未来收益。

 ## 算法演练

 我们仅处理两个数组中的 (0, 1, 2) 计数。 

1. 第一个匹配尽可能多的 2`a`1s 内`b`尽可能。 每对这样的贡献+2。 

这是最强的正向互动`a > b`。 
2. 下一场比赛还剩2秒`a`其中有 0`b`。 每个贡献+0？ 实际上，由于 2 > 0，贡献为 +0 产品 = 0，因此这些是中性的，但有助于避免以后出现更糟糕的配对。 
3.然后匹配1`a`其中有 0`b`。 每个人也贡献+0，也是中立的，但在战略上有用。 

至此，我们已经用尽了所有积极或中立的机会`a > b`。 

现在我们处理不可避免的损失：

 1. 剩余2秒`b`会容易受伤`a`除非我们可以牺牲 0`a`。 我们匹配 0`a`2英寸`b`，这是 -0 贡献，但可以防止未来出现更糟糕的配对。 这实际上是中立的。 
2. 接下来我们处理 1 vs 2，其中`a < b`，每对产生 -2。 我们匹配剩余的 1s`a`2秒内`b`。 
3. 最后，任何剩余的不匹配对都是相等的或无害的并且贡献为 0。 

关键的想法是，我们总是首先消耗最有价值的积极配对，然后尽早消除最具破坏性的消极配对。 

### 为什么它有效

 由于只有三个值，因此每个配对都属于恒定数量的交互类型之一。 每种类型都有固定的贡献。 贪婪顺序首先优先考虑较高边际收益的交互。 一旦跳过高价值配对，以后就永远无法恢复，因为相应的元素只会参与相同或更差的结果。 这创建了一个交换参数：任何与此顺序的偏差都可以交换回来，而不会减少总和，从而确保最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        x1, y1, z1 = map(int, input().split())
        x2, y2, z2 = map(int, input().split())
        
        # a: 0->x1, 1->y1, 2->z1
        # b: 0->x2, 1->y2, 2->z2
        
        # Step 1: 2 in a vs 1 in b => +2 each
        take = min(z1, y2)
        z1 -= take
        y2 -= take
        score = 2 * take
        
        # Step 2: 2 in a vs 0 in b => 0 contribution
        take = min(z1, x2)
        z1 -= take
        x2 -= take
        
        # Step 3: 1 in a vs 0 in b => 0 contribution
        take = min(y1, x2)
        y1 -= take
        x2 -= take
        
        # Step 4: 1 in a vs 2 in b => -2 each
        take = min(y1, z2)
        y1 -= take
        z2 -= take
        score -= 2 * take
        
        # remaining pairs contribute 0
        out.append(str(score))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码直接反映了贪婪交互顺序。 我们积累价值的唯一地方是第一步和第四步，因为这些是唯一以影响总和的方式产生非零贡献的相互作用。 中间步骤的存在纯粹是为了从竞争中删除元素，以便以后不会意外地形成更糟糕的配对。 

一个微妙的点是我们从不明确模拟配对位置。 这是安全的，因为最优性仅取决于计数，而不取决于排序。

 ## 边缘情况

 一种极端情况是一个序列仅包含零。 在这种情况下，无论排列如何，每个配对都为零。 该算法立即跳过所有有意义的贡献，因为每个`min`涉及正数的计数变为零，总分为零。 

当一个序列严重偏向 2 而另一个序列严重偏向 1 时，就会出现另一种边缘情况。该算法提取所有正值`2 vs 1`首先匹配，确保在解决任何剩余的不平衡之前获得最大收益。 任何剩余元素都会落入中性或不可避免的负配对，而贪婪排序已经将其最小化。 

最后的边缘情况是两个序列中的值的计数相同。 每个贪婪步骤都会消耗对称量，并且不会产生净收益或净损失，因此输出保持为零。
