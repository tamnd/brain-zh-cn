 ## 解决方案
 ## 问题理解

 我们得到一个大小为的隐藏数组$n$，但该数组不能直接访问并且可以任意排列。 唯一的结构保证是，如果我们对其元素进行排序，它们会形成一个完美的算术级数，并具有严格的正公差。 所以值的多重集看起来像$$m,\; m+d,\; m+2d,\; \dots,\; m+(n-1)d$$但我们不知道$m$,$d$，或排列。 

我们可以使用两种工具与数组进行交互。 一种工具可以让我们读取所选索引处的值。 另一个工具是阈值预言机，它告诉我们数组中的任何元素是否严格大于给定值。 每个查询都很昂贵，而且我们最多只能进行 60 个查询，因此任何解决方案都必须非常积极地提取全局结构，而不是直接检查数组。 

输出要求恢复最小值$m$以及共同的区别$d$。 一次$m$众所周知，差异是由于最大元素是$m + (n-1)d$。 

关键约束是查询限制。 对所有索引进行线性扫描是不可能的，因为$n$可以达到$10^6$。 即使指数的对数方法也是无关紧要的，因为我们没有指数的排序。 唯一有意义的杠杆来自价值预言机，它允许对最大值进行全局推理。 

一个天真的错误是假设我们可以使用阈值查询直接找到最小值。 神谕只回答“有没有超过$x$？”，它本质上是单边的，只能访问分布的最大一侧。另一个常见的陷阱是尝试重建排列或搜索邻居，如果没有位置结构，这是不可能的。

 当所有采样索引都错过真正的最小值或最大值时，就会出现边缘情况。 由于值分布在一个大数组中，任何纯粹依赖均匀随机采样而不考虑覆盖范围的策略在对抗性放置下都可能会失败。 

## 方法

 暴力策略将尝试查询每个索引并读取所有值，然后对它们进行排序并计算差异。 这是非常正确的，因为它直接重建数组。 但是，它立即失败，因为查询所有$n$指数成本$O(n)$，最多可达 100 万个查询，远远超出了 60 个允许的限制。 

关键的观察是我们不需要整个数组，只需要极值和间距。 阈值预言机为我们提供了强大的功能：我们可以对值进行二分搜索以找到最大元素。 一旦知道了最大值，算术级数结构就会将整个问题分解为寻找最小值，因为$$d = \frac{\max - \min}{n-1}.$$我们不能直接二分查找最小值，因为oracle不支持“是否有元素小于$x$“。所以唯一缺少的部分是获得最小值的可靠估计。由于数组是一个排列，因此每个索引都同样可能包含最小值。对少量索引进行采样给出了达到两个极端的很高概率，并且总共 60 个查询，我们可以提供足够的样本，使失败概率在实践中可以忽略不计，并在预期解决方案中被接受。

 因此，最终策略是最大值的确定性提取和最小值的概率采样的组合，利用严格的算术结构来恢复完整的级数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 查询所有索引 |$O(n)$查询 |$O(1)$| 不可能（60 限制）|
 | 最大+随机采样|$O(60)$查询 |$O(1)$| 已接受 |

 ## 算法演练

 ### 1. 使用二分查找查找最大值

 我们使用预言机来回答元素是否大于$x$存在。 这是单调的$x$，所以我们可以二分查找最大值$M$在$[0, 10^9]$。 每一步都会将搜索空间减半，需要大约 30 个查询。 

在此步骤结束时，我们知道隐藏数组中的确切最大值。 

### 2. 使用剩余的查询对索引进行采样并收集值

 我们随机查询索引并存储它们的值。 每个查询都会揭示隐藏多重集的一个元素。 有了足够的样本，我们期望观察到广泛的算术级数，包括接近两端的值。 

我们保持最小的观测值$m'$。 这充当真正最小值的候选者。 

### 3. 计算公差

 一旦我们有$M$和候选最小值$m'$，我们计算：$$d = \frac{M - m'}{n-1}.$$这是从算术级数的定义得出的，因为排序的数组正好跨越$n-1$步数相等。 

### 4.输出结果

 我们打印$m'$和$d$作为答案。 

### 为什么它有效

 正确性依赖于多重集的刚性结构。 二分查找步骤保证$M$是准确的。 剩下的不确定性只是真正的最小值。 由于级数中的所有值都是不同的且间隔均匀，因此在均匀随机性下不太可能丢失恒定数量的随机样本中的最小值。 一旦捕获到任何正确的最小值，算术级数属性就会强制计算出唯一的值$d$，它必须与原始隐藏序列匹配。 

## Python 解决方案```python
import sys
import random

input = sys.stdin.readline

def ask_more(x):
    print(">", x)
    sys.stdout.flush()
    return int(input())

def ask_idx(i):
    print("?", i)
    sys.stdout.flush()
    return int(input())

def find_max(n):
    lo, hi = 0, 10**9
    while lo < hi:
        mid = (lo + hi + 1) // 2
        if ask_more(mid):
            lo = mid
        else:
            hi = mid - 1
    return lo

def solve():
    n = int(input())

    # 1) find maximum value
    mx = find_max(n)

    # 2) sample indices to estimate minimum
    samples = 50
    best = 10**18

    for _ in range(samples):
        i = random.randint(1, n)
        val = ask_idx(i)
        best = min(best, val)

    mn = best

    d = (mx - mn) // (n - 1)

    print("!", mn, d)
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该代码将交互分为两个原语：索引查询和阈值查询。 二分搜索是通过值而不是索引来实现的，因为全局只能使用值排序。 

随机采样阶段是唯一的概率部分。 它故意使用大多数剩余的查询来最大化捕获最小元素的机会。 

最后的算术步骤使用整数除法，这是安全的，因为输入保证了完美的算术级数。

 ## 边缘情况

 关键的边缘情况是很少对最小元素进行采样。 如果数组大小很大且随机索引不幸运，则所有采样值可能严格高于真实最小值。 在这种情况下，算法会高估$m$，产生一个不正确的$d$。 这是该策略唯一的失败模式，可以通过使用查询的全部预算来最大化覆盖范围来缓解这种情况。 

另一个边缘情况是$n = 2$。 在这里，任何采样值都会立即确定另一个端点，并且计算出的差值必须处理除以$n-1 = 1$，这完全避免了歧义。 

第三种边缘情况是，除了一个罕见的最小值出现之外，所有采样索引都返回最大值。 该算法仍然有效，因为单个正确的最小样本足以唯一地修复整个级数。 

这些案例强调，正确性完全取决于采样期间至少捕获一个真实的极端值，这在允许的查询预算下是可行的。
