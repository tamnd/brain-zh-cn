 ## 解决方案
 ## 问题理解

 我们有三个对葡萄喜好不同的人，还有三堆葡萄。 

安德鲁想要的正是第一种葡萄，绿葡萄。 如果他需要的话`x`葡萄，必须全部来自青堆。 

德米特里不喜欢黑葡萄。 他可以吃绿色或紫色的葡萄。 他至少需要`y`这两种颜色的葡萄总数。 

米哈尔没有任何限制。 他可以吃任何颜色的葡萄并且至少需要`z`葡萄。 

输入给出所需的金额`x`,`y`， 和`z`，后跟可用计数`a`,`b`， 和`c`绿色、紫色和黑色的葡萄。 我们必须确定是否存在某种满足所有三个人的分布。 

限制很小。 每个值最多是`10^5`，并且只有一个测试用例。 即使对多种可能性进行强力搜索也很合适，但问题的结构允许更简单的恒定时间解决方案。 

棘手的部分是颜色具有不同程度的灵活性。 青葡萄是最受限制的资源，因为安德鲁只能吃青葡萄。 紫葡萄更灵活，因为德米特里可以使用它们。 黑葡萄只有米哈尔最灵活，因为没有其他人可以使用它们。 粗心的实施可能只检查葡萄总数而忽略这些限制。 

考虑这个例子：```
3 1 1
2 100 100
```葡萄总数绰绰有余，但安德鲁需要三颗青葡萄，而只有两颗存在。 正确答案是`NO`。 

另一个微妙的情况是安德鲁可以满意，但德米特里不能。```
2 5 1
2 4 100
```给安德鲁他的两颗绿葡萄后，就没有绿葡萄了。 德米特里只能使用四颗紫葡萄，这还不足以达到五颗。 正确答案是`NO`。 

第三种情况是安德鲁和德米特里都可以满意，但米哈尔不能。```
1 1 10
1 1 8
```安德鲁拿了一颗绿葡萄。 德米特里拿了一颗紫葡萄。 什么都没有剩下，所以米哈尔收到了零颗葡萄，尽管他需要十颗。 正确答案是`NO`。 

这些示例表明分配顺序很重要。 应首先检查受限制最多的消费者。 

## 方法

 一个蛮力的想法是尝试一切可能的方法在安德鲁和德米特里之间分配绿葡萄，然后检查剩下的葡萄是否能让其他人满意。 由于每堆尺寸可以达到`10^5`，枚举所有分布最多需要大约`10^5`的可能性。 在这里，这仍然是可以管理的，但它不必要地复杂。 

关键的观察是这些限制形成了一个自然的层次结构。 

安德鲁是最受限制的，因为他只能吃绿葡萄。 如果少于`x`绿葡萄，没有解决方案。 

一旦安德鲁收到了他的葡萄，任何剩余的绿葡萄就可供德米特里使用。 德米特里可以使用绿葡萄和紫葡萄。 如果剩余的绿色葡萄加上所有紫色葡萄的总量小于`y`，不存在解。 

当安德鲁和德米特里满意后，剩下的每一颗葡萄，无论颜色如何，都可以送给米哈尔。 如果剩余葡萄总数至少为`z`，存在有效分布。 

因为每一步都会贪婪地首先满足最受限制的人，所以我们永远不会浪费以后可能需要的资源。

 | 蛮力 | O(a) | O(1) | O(1) | 已接受但没有必要 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 检查是否至少有`x`绿葡萄。 如果`a < x`， 输出`NO`因为安德鲁无法满足。 
2. 通过减去给安德鲁他需要的葡萄`x`从`a`。 剩下的绿葡萄现在可供德米特里使用。 
3.检查剩余的绿葡萄加上所有的紫葡萄是否可以满足德米特里。 如果`a + b < y`， 输出`NO`。 
4. 给德米特里他需要的葡萄。 由于德米特里可以先使用绿葡萄，然后使用紫葡萄，所以计算吃完后还剩下多少葡萄`y`来自联合池的葡萄。 
5.让`remaining = a + b - y + c`。 这是留给米哈尔的葡萄总数。 
6.如果`remaining >= z`， 输出`YES`。 否则输出`NO`。 

### 为什么它有效

 安德鲁的要求是最严格的。 任何有效的解决方案都必须保留`x`给他青葡萄。 首先检查这一点是强制性的。 

安德鲁满意后，德米特里可以使用剩余的所有非黑色葡萄。 如果剩余的绿葡萄和紫葡萄的总数量少于`y`，任何安排都无济于事，因为这些是德米特里唯一接受的颜色。 

一旦安德鲁和德米特里满意，米哈尔就可以吃掉剩下的葡萄。 那时，只有剩余葡萄的总数很重要。 如果至少`z`剩下的葡萄，无论颜色如何，米哈尔都可以随时拿走。 

每一项检查都恰好对应了一个必要条件，并且在首先满足更受限制的人之后，这些条件也是充分的。 因此该算法是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

x, y, z = map(int, input().split())
a, b, c = map(int, input().split())

if a < x:
    print("NO")
    sys.exit()

a -= x

if a + b < y:
    print("NO")
    sys.exit()

remaining = a + b - y + c

if remaining >= z:
    print("YES")
else:
    print("NO")
```第一个条件涉及安德鲁。 如果没有足够的青葡萄，答案是不可能的。 

减去安德鲁的葡萄后，变量`a`代表剩余的绿色葡萄。 德米特里可以将它们与所有紫葡萄一起使用，所以第二个条件检查`a + b`。 

表达式`a + b - y`代表 Dmitry 准确收到后还剩下多少绿色和紫色葡萄`y`葡萄。 添加`c`包括所有黑葡萄，只有米哈尔可能需要。 

该实现避免了显式构建分布，因为只有计数很重要。 不需要循环，所有算术都很容易符合正常整数范围。

 ## 边缘情况

 ### 青葡萄不够

 输入：```
3 1 1
2 100 100
```该算法立即检查`a < x`。 自从`2 < 3`，它输出`NO`。 

解决办法是不可能的，因为安德鲁只接受青葡萄。 额外的紫色或黑色葡萄无法弥补。 

### 足够的绿葡萄，但对德米特里来说还不够

 输入：```
2 5 1
2 4 100
```安德鲁吃了两颗绿葡萄，留下：```
a = 0
b = 4
```算法检查`a + b < y`:```
0 + 4 < 5
```这是真的，所以答案是`NO`。 

德米特里不能吃黑葡萄，所以大黑堆是无关紧要的。 

### 对于安德鲁和德米特里来说足够了，但对于米哈尔来说还不够

 输入：```
1 1 10
1 1 8
```安德鲁之后：```
a = 0
```德米特里吃了一颗葡萄：```
a + b - y = 0
```剩下的葡萄等于：```
0 + 8 = 8
```自从`8 < 10`，Michal 无法满足，算法输出`NO`。 

这证实了满足前两个人并不自动意味着有足够的葡萄留给第三个人。
