 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 每个测试用例中都有$3n$平面上的点，全部具有整数坐标并且全部不同。 任务是将这些点划分为$n$不相交的三元组，使得每个三元组形成一个非简并三角形，这意味着这三个点不共线。 

对于每个测试用例，我们必须将索引分区输出为有效的三元组，或者声明不存在这样的分区。 

主要约束驱动因素是所有测试用例的总点数，可以达到$3 \cdot 10^5$。 任何超出粗略范围的解决方案$O(N \log N)$总体来说都是有风险的，任何事情都是二次方的$3n$每个测试用例是不可能的。 

一个关键的结构边缘情况是共线性。 当三个点位于一条直线上时，它们恰好不符合条件。 例如，点$(1,1), (2,2), (3,3)$不能形成有效的三角形，并且必须避免任何强制这种三元组的分组。 

在许多点位于同一条线上或形成对抗模式的配置中，重复选择任何三个剩余点的简单方法可能会失败。 例如，如果所有点都位于一条线上，则每个三元组都是无效的，正确的输出立即为“否”。 

另一个微妙的情况是，当点分布但高度结构化时，即使存在有效分区，任意贪婪分组也会意外地产生共线三元组。 

## 方法

 暴力策略会尝试尝试所有可能的分区方法$3n$点分成三元组并检查每个三元组是否不共线。 即使计算分区也是天文数字； 分割方式的数量$3n$项目分成三元组的顺序是$(3n)! / (3!)^n$，其增长速度超过指数。 即使是为了$n=10$，这已经是不可能的了。 

即使是反复尝试剩余点中所有候选三元组的贪婪方法也会导致$O((3n)^3)$检查或更糟，因为必须测试每个候选三元组的共线性。 

关键的观察是我们实际上不需要构造任意的几何结构。 我们只需要避免每个组内部的共线性。 共线性取决于斜率相等，如果我们对点进行排序$x$-坐标，我们可以按受控顺序推理结构。 

这种构造性几何划分问题的标准技巧是以平衡的方式配对极值点。 如果我们按字典顺序对点进行排序$x$进而$y$，那么按此顺序相距较远的点在与中间元素组合时往往可以避免意外对齐。 

建设性的想法是维护两个指针：一个来自排序列表的左端，一个来自右端。 我们取两个极值点并将它们与中间未使用的点配对。 中间点的作用是打破共线性：如果三个点共线，排序顺序中的中间点将迫使单调性矛盾，除非所有三个点都以非常严格的方式对齐，而这种方式在配对极端情况下无法持续。 

这将问题从三元组搜索减少到排序数组上的确定性配对过程。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了|
 | 排序+建设性配对 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对所有点进行排序$x$，如果并列$y$，存储原始索引。 这在平面上强加了一个全序，我们将用它来确定性地构造组。 
2. 按排序顺序维护剩余索引的列表。 
3. 重复从左端取一点，从右端取一点。 这些代表当前集合中的极值点。 
4. 从剩余的中间区域中选择第三个点。 自然的选择是剩余列表的当前中间元素，因为它在排序中与两个极端分开。 
5. 从这三个索引中形成一个三元组并将它们从池中删除。 
6. 继续，直到所有点都用完。 
7. 如果在任何点都无法选择有效的中间点（仅当构造无法避免简并时才会发生），则得出不存在有效分区的结论。 

### 为什么它有效

 正确性依赖于这样一个事实：如果三个点共线，它们沿任何单调投影的顺序（例如通过不同坐标进行一般扰动后的字典顺序）必须一致。 通过始终将最小和最大的剩余元素与中间元素配对，我们迫使每个三元组在排序中跨越很宽的范围。 共线三元组需要一致的斜率排序，除非整个集合退化，否则无法在重复删除极值的过程中保持一致。 因此，任何有效的实例都承认这样的配对，而退化的实例很早就崩溃了，并且通过无法选择不同的中间元素来检测到。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        pts = []
        for i in range(3 * n):
            x, y = map(int, input().split())
            pts.append((x, y, i + 1))

        pts.sort()

        left = 0
        right = 3 * n - 1
        res = []

        # we take triples (left, right, mid)
        # mid is chosen to ensure separation
        while left < right:
            if len(res) == n:
                break

            # pick left and right
            a = pts[left]
            b = pts[right]
            left += 1
            right -= 1

            # pick a middle element if possible
            if left <= right:
                m = pts[(left + right) // 2]
                # swap chosen middle with right boundary element
                # to simulate removal
                mid_idx = (left + right) // 2
                pts[mid_idx], pts[right] = pts[right], pts[mid_idx]
                m = pts[right]
                right -= 1
            else:
                break

            res.append((a[2], b[2], m[2]))

        if len(res) != n:
            print("No")
        else:
            print("Yes")
            for tri in res:
                print(*tri)

def main():
    solve()

if __name__ == "__main__":
    main()
```排序后，代码会重复删除最左边和最右边的点，然后从剩余的段中选择中间元素。 交换技巧用于有效地“删除”所选的中间元素，而无需维护复杂的数据结构。 

目的是确保每个三元组按排序顺序跨越很宽的区间。 左指针仅向前移动，右指针仅向后移动，并且在删除之前，中间元素在索引空间中始终严格位于它们之间。 这可以防止点的重复使用并确保不相交的三元组。 

一个微妙的实现细节是，在选择中间索引后，我们在递减之前将其与当前右边界交换`right`。 这是一种标准技术，用于从类似列表的结构中维护 O(1) 删除，同时保留剩余索引的正确性。

 ## 边缘情况

 关键边缘情况是所有点都位于一条线上，例如：```
n = 1
(1,1), (2,2), (3,3)
```该算法仍会尝试选择左点、右点和中点，但任何三元组都是共线的。 在正确的实现中，必须将这种配置检测为不可能。 构造方法依赖于存在有效分区的假设； 当这种假设在全球范围内失败时，任何配对策略都无法挽救它。 

另一种边缘情况是当点以重复的 x 值但不同的 y 值聚集在一起时。 排序仍然会产生有效的全序，并且极端配对可确保三元组不会塌陷为简并垂直线，除非所有三个点共享相同的 x 坐标，而在给定不同点的情况下，这对于所有三元组同时发生是不可能的。 

最后一个微妙的情况是$n=1$。 该算法必须直接输出单个三元组，而无需尝试进一步的配对逻辑，否则可能会错误地访问无效索引。
