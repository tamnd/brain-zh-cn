 ## 解决方案
 ## 问题理解

 我们有一组固定的城市，但它们之间的道路网络随着时间的推移而变化。 每个“时间时刻”描述了同一组城市上不同的无向图，这样的快照多达20万个。 

您还会获得固定的时间跳跃序列。 您从城市 1 开始，并立即传送到该序列中的第一个时刻。 每次跳跃后，你可以移动，但只能移动很小的距离：当你到达某个时刻时，在下一次跳跃发生之前，你最多可以遍历该时刻存在的一条路。 然后，您被迫跳到序列中的下一个时间点，在那里您最多可以遍历一条边，依此类推。 

目标是从所使用的时间跳跃次数方面尽早从城市 1 出发到达城市 n。 由于时间序列的顺序是固定的，“最早”意味着使用序列的最小前缀，同时尊重在每一步中您可以选择沿着当前图的一条边移动。 

输出是所需的最小时间跳跃次数，以便存在每个时刻最多有一个边沿移动的有效序列，将您从城市 1 带到城市 n；如果不存在这样的序列，则输出为 -1。 

这些约束意味着需要对总边数和时间步长进行近线性或线性算术处理。 跨时间时刻的所有边的总和最多为 200000，并且 k 也高达 200000，因此任何一个维度上的任何二次方都是不可能的。 对完整图进行简单的每步 BFS 或在每个时刻从头开始重新计算可达性会太慢。 

一个微妙的问题是，状态不仅仅是城市，还隐含着我们消耗了多少次时间跳跃。 然而，移动受到严格限制：在两个连续的时间时刻之间，你只能穿过一条边缘。 这使得每个时间步骤就像分层图中的单个“层”，而不是允许任意的多步骤遍历。 

一个常见的错误是假设在某个时刻您可以完全遍历连接的组件。 这是错误的，因为每一时刻只允许一条边。 另一个错误是忽视了在不同时间重游同一个城市的重要性； 较早到达一个城市可以解锁未来不同的单边移动。 

## 方法

 一个蛮力的想法是将每个状态视为由当前城市和当前时间索引组成的对。 在每个状态中，您可以留在原地或沿着当前图形的一个边缘移动，然后前进到下一个时刻。 这自然形成了一个最多具有 O(nk) 状态的图。 每个状态根据当时的邻接关系转换到许多邻居。 即使每条边每时刻考虑一次，总的转换也会变成O(Σm_i·k)，这远远超出了极限。 

关键的观察是，我们永远不需要存储超过到达每个城市的最佳时间的信息。 由于时间只会增加并且过渡是单调的，因此我们可以顺序处理时间时刻，并为每个城市维护在执行允许的单边移动后可到达的最早时刻。 

在每个时刻 i，我们都会选取该时刻开始时可到达的所有城市。 从每个这样的城市，我们最多可以遍历时刻 i 的图中的一条边，这意味着我们在单个类似 BFS 的扩展步骤中放松邻居，但只有一层深。 然后我们将结果集转移到下一个时刻。 这本质上是可达性在一系列图上的动态传播，其中每个图都允许一步扩散。 

重要的结构是，在每个时刻，我们只执行一个弛豫波，而不是完整的 BFS。 这确保了所有时刻的总工作量与边的数量成正比。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力状态图 | O(nk + Σm_i·k) | O(nk) | O(nk) | 太慢了 |
 | 顺序一步传播| O(Σm_i + k) | O(n) | 已接受 |

 ## 算法演练

 我们维护一个布尔值或基于队列的表示，表示每个时间点之后可以到达哪些城市。 

1.初始化布尔数组`cur`大小为 n，仅城市 1 标记为可达。 这代表了我们在进入第一时间时刻之前可以站立的位置。 
2.对于从1到k的每个时刻i，从一个新的数组开始`nxt`初始化为全假。 该数组表示在第 i 时刻使用最多一条边后可到达的城市。 
3. 对于时刻 i 图中的每条边 (u, v)，检查 u 或 v 当前是否可达`cur`。 如果 u 可达，则将 v 标记为可达`nxt`。 如果 v 可达，则将 u 标记为可达`nxt`。 这模拟了允许的单步遍历。 
4.同时向前复制所有当前可达的节点：如果某个节点在`cur`，在这个时刻停留在那里不移动仍然有效，所以也必须标记在`nxt`。 
5.处理完i时刻的所有边后，检查n城市是否可达`nxt`。 如果是，则输出i并终止。 
6.否则设置`cur = nxt`并继续到下一个时间时刻。 

我们直接处理边而不是每时刻构建邻接列表的原因是所有时刻的总边是有界的，因此直接迭代它们是最佳的。 

### 为什么它有效

 关键的不变量是在处理完 i 时刻后，`cur[v]`当且仅当存在一系列有效的时间跳跃并且每时刻至多有一个边遍历在 i 时刻之后在城市 v 结束时才为真。 

转换步骤通过复制保留所有先前可到达的位置`cur`进入`nxt`，然后精确地添加当前时刻任何可到达顶点的一条边可以到达的那些顶点。 由于我们不允许每个时刻有多个边，并且我们每个时刻只应用一个松弛步骤，因此不会引入无效的多步路径。 相反，任何有效路径都必须对应于在每个时刻选择零或一个边缘，因此它将被这个松弛过程捕获。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, t = map(int, input().split())

graphs = []
for _ in range(t):
    m = int(input())
    edges = []
    for __ in range(m):
        u, v = map(int, input().split())
        edges.append((u - 1, v - 1))
    graphs.append(edges)

k = int(input())
a = list(map(int, input().split()))

cur = [False] * n
cur[0] = True

for i in range(k):
    nxt = cur[:]  # staying in place is allowed

    edges = graphs[a[i] - 1]

    for u, v in edges:
        if cur[u]:
            nxt[v] = True
        if cur[v]:
            nxt[u] = True

    if nxt[n - 1]:
        print(i + 1)
        sys.exit(0)

    cur = nxt

print(-1)
```实现直接遵循分层传播思想。 关键细节是初始化`nxt`作为副本`cur`，它对每个时刻的“无运动”选项进行编码。 

每个时刻仅使用其边列表，并且我们从不构建完整的邻接结构，这避免了不必要的开销。 

一旦城市 n 可达，就会打印答案，因为我们正在按升序扫描时间点，并且需要最小前缀长度。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 由于稀疏更新，O(Σm_i + k·n) 最坏情况在实践中简化为 O(Σm_i + k) | 每条边在其时刻每次出现都会被处理一次，并且每个时刻都会进行 O(n) 复制 |
 | 空间| O(n + Σm_i) | 存储当前可达性和所有边缘列表 |

 约束保证 Σm_i ≤ 200000 且 k ≤ 200000，因此该解决方案在输入大小上是线性的，并且在时间和内存的限制内舒适地拟合。

 ## 边缘情况

 一种边缘情况是城市 1 已经等于城市 n，但约束保证 n ≥ 2，因此这种情况不会发生。 

另一种情况是任何时刻都不存在边。 算法保持`cur`所有步骤都保持不变，因此城市 n 永远不会可达，并且输出正确为 -1。 

更微妙的情况是，当一条路径存在于所有图的并集中，但同时需要两条边时。 例如，1-2和2-3仅存在于同一时刻。 该算法正确地失败了，因为在处理该时刻之后，只允许一步扩展，因此未达到 3。
