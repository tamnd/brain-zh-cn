 ## 解决方案
 ## 问题理解

 我们得到了一系列问题，每个问题都有一个非负的难度值和一个总的心理预算$S$。 我们可以选择总难度不超过的问题子集$S$，这些被认为是“正常解决”。 

完成初始选择后，我们可以执行一个称为“洞察”的附加操作。 这一见解让我们可以免费再选择一个问题，但前提是在已经解决的问题中至少有一半的难度不小于所选问题的难度。 一旦解决了这个额外问题，该过程就结束。 

目标是最大化解决的问题总数，计算最初解决的子集和一个可能的奖励问题。 

输入大小可达$3 \cdot 10^5$排除任何尝试所有子集或执行昂贵的状态探索的解决方案。 甚至$O(n^2)$方法已经太大了，因为排序加上二次扫描会超出时间限制。 这立即提出了一种基于排序和线性或近线性遍历的策略，其中每个候选结构以摊余常数或对数时间进行评估。 

问题的一个微妙方面是，奖励条件取决于所选子集中难度的“相对排序”，而不仅仅是它们的总和。 另一个微妙的情况是当初始子集为空时：条件变为空真，这意味着任何单个问题都可以被视为奖励动作。 

一种经常失败的简单方法是贪婪地获取下可能的最小子集$S$然后尝试添加尽可能多的奖金。 这是因为“至少一半”约束取决于子集中值的分布，而不仅仅是其大小或总和。 

例如，如果所选子集偏向非常小的值，则即使预算在允许更平衡子集的其他配置中保持未使用，适度大的奖励候选也可能会失败。 

## 方法

 强力策略是枚举问题的所有子集，计算它们的总和，并为每个可行的子集尝试满足类似中值约束的每个可能的奖励候选者。 这在概念上是正确的，因为它直接模拟规则，但其成本是指数级的$n$。 即使限制为固定大小的子集仍然会导致组合爆炸，因为检查所有大小 -$k$子集需要$\binom{n}{k}$运营。 

关键的观察结果是，奖励条件仅取决于所选子集中有多少元素大于或等于奖励候选。 这本质上是一个中值式约束，表明任何选定子集的内部结构都可以通过排序的顺序统计来理解。 

一旦我们对数组进行排序，任何最佳解决方案都可以假设选择一个子集，该子集也与排序顺序中的某些前缀或精心构造的选择一致。 成本约束表明对于固定的子集大小$k$，最好的候选者是采取$k$最便宜的可用问题。 然后我们检查这个子集是否可以支持某个等级的奖励元素，这减少了检查它有多少元素高于阈值。 

这将问题转化为单调结构：当我们增加子集大小时，总和会增加，但满足“一半不小于 x”约束的潜力也会增加$x$。 这使得能够进行两指针或基于前缀的评估，我们可以有效地测试每个可能的子集大小并计算可实现的最佳奖励。

 | --- | --- | --- | --- |
 | 蛮力 |$O(2^n \cdot n)$|$O(n)$| 太慢了 |
 | 排序前缀+贪心检查|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 按非降序对困难数组进行排序。 这确保了任何前缀都对应于选择固定数量问题的最便宜的方法。 
2. 构建前缀和，以便我们可以计算第一个的总成本$k$恒定时间内的问题。 这使我们能够快速测试子集大小在预算范围内是否可行$S$。 
3. 对于每个可能的数字$k$最初解决的问题，确定长度的前缀$k$最多有总和$S$。 没有的话就大一点$k$也将是不可行的，因为数组已排序。 
4.对于每一个可行的$k$，确定最佳可能的奖励元素。 我们希望解决的问题总数尽可能多，因此我们的目标是选择尽可能大的奖励元素，同时仍然满足相对于所选子集的约束。 
5. 检查候选人奖金是否值$x$适用于子集大小$k$，我们至少需要$\lceil k/2 \rceil$子集中至少有值的元素$x$。 在排序的前缀中，这对应于检查前缀中有多少个元素$\ge x$，可以通过二分查找来计算。 
6.而不是检查所有$x$，我们只需要考虑数组中存在的值作为奖励的候选值，因为任何最佳选择都可以映射到现有的难度级别而不失一般性。 
7. 对于每个候选奖励值，计算最小前缀大小$k$两者都适合$S$并满足该奖金的类似中值条件。 跟踪最大值$k+1$。 

### 为什么它有效

 排序后，任意最优选择$k$最小化成本的元素恰好是长度的前缀$k$。 任何偏差都会用更大的元件替换所选元件，从而增加成本而不提高可行性。 奖金条件仅取决于相对于阈值的计数，该阈值保留在排序结构下。 因此，将问题简化为前缀评估并不排除任何最佳解决方案，并且检查所有相关阈值可以保证我们找到最佳的可能扩展。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, S = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + a[i]

    def feasible(k):
        return prefix[k] <= S

    # best answer without bonus
    ans = 0
    for k in range(n + 1):
        if feasible(k):
            ans = max(ans, k)
        else:
            break

    # try each value as bonus threshold
    # we precompute positions of each value
    from collections import defaultdict
    pos = defaultdict(list)
    for i, v in enumerate(a):
        pos[v].append(i)

    # iterate over all possible bonus values
    for i in range(n):
        x = a[i]

        # find how many elements in prefix can support x
        # we want subset of size k such that at least ceil(k/2) elements >= x
        # among prefix k, count of >= x is k - lower_bound(x)
        lo, hi = 0, n
        best_k = 0

        while lo <= hi:
            mid = (lo + hi) // 2
            if not feasible(mid):
                hi = mid - 1
                continue

            # count of elements >= x in prefix mid
            import bisect
            idx = bisect.bisect_left(a, x)
            cnt_ge = mid - min(mid, idx)

            if cnt_ge * 2 >= mid:
                best_k = mid
                lo = mid + 1
            else:
                hi = mid - 1

        if best_k > 0:
            ans = max(ans, best_k + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```代码的第一部分对数组进行排序并构建前缀和，以便可以在恒定时间内测试预算下的可行性。 变量`ans`跟踪最佳解决方案而不使用奖励动作。 

第二部分迭代可能的奖励阈值并对前缀大小执行二分搜索$k$。 可行性检查结合了两个约束：总和$S$以及要求至少一半的所选前缀元素至少是候选奖励值。 合格元素的计数是使用排序数组上的二分搜索来计算的。 

一个微妙的点是，用于成本的前缀和用于奖金条件的分布引用相同的排序顺序，因此我们可以为这两个检查重用单个数组。

 ### 示例 1

 输入：```
6 12
4 2 1 3 6 5
```排序后的数组是`[1,2,3,4,5,6]`，前缀和是`[1,3,6,10,15,21]`。 

我们评估可行的前缀：

 | k | 前缀和| 可行|
 | --- | --- | --- |
 | 1 | 1 | 是的 |
 | 2 | 3 | 是的 |
 | 3 | 6 | 是的 |
 | 4 | 10 | 10 是的 |
 | 5 | 15 | 15 没有|

 所以没有奖金的话，最好是4。 

现在考虑奖金选择。 例如，采取$x=3$。 我们可以选择大小为 4 的前缀：`[1,2,3,4]`。 其中，2个元素≥3？ 其实只是`[3,4]`，因此四分之二满足条件，允许奖金。 然后我们可以采取`5`或者`6`根据可行性推理作为奖金； 最好的扩展总共产生 5。 

### 示例 2

 输入：```
7 15
4 3 2 1 100 1000000000
```排序：`[1,2,3,4,100,1000000000]`。 

前缀可行性：

 k=4和为10，可行； k=5总和是110，不可行。 

所以基本答案是4。 

尝试奖金，我们可以选择一个像 100 这样的大值。带有前缀`[1,2,3,4]`，至少有一半 ≥100 是假的，因此失败。 使用较小的阈值，例如 3，前缀`[1,2,3,4]`有两个元素≥3，满足条件，所以我们可以根据可行性逻辑取奖金100或1e9，总共4。 

这证实了该算法平衡了预算约束和结构约束。

 ## 边缘情况

 当$n=1$，算法正确处理这两个结果：如果$a_1 \le S$，前缀大小 1 是可行的，并且还可能允许奖励（不会有效地将计数增加到超过 1），否则答案为 0。 

当所有元素都相等时，对于任何前缀来说，类似中位数的条件都变得微不足道，因为每个元素都满足等于该值的任何阈值。 该算法正确地识别出最佳解决方案是完整前缀或完整前缀加奖金，具体取决于预算可行性。 

什么时候$S$非常大，所有前缀都是可行的，并且解决方案简化为最大化奖金适用性。 排序结构确保始终考虑最大前缀，并且约束纯粹与阈值条件有关，这是通过按数组顺序检查值来处理的。 

当值高度倾斜时，例如一个极大的元素和许多小的元素，该算法可以避免过早错误地采用大元素，因为前缀可行性首先强制执行成本最小化，确保成本和奖励推理之间的正确分离。
