 ## 解决方案
 ## 问题理解

 我们得到了一组独立组件，每个组件都以一定的概率正确工作。 仅当至少有阈值数量的这些组件工作时，系统才会成功。 我们可以通过在组件之间分配固定数量的“培训资源”来改进组件。 每单位资源都会使所选组件的成功概率增加一个单位，最多为 1。 

任务是以最大化至少 K 个组件成功的概率的方式跨组件分配有限的资源。 

输入由多个测试用例组成。 对于每个测试用例，我们都会收到组件的数量、所需的工作组件的最小数量、改进单元的总预算以及所有组件的初始成功概率。 

输出是在优化分配改进单元后至少 K 个组件起作用的最大可实现概率。 

N 方面的约束很小，N 最多为 50，这强烈表明每个测试用例 O(N3) 甚至 O(N⁴) 式的解决方案可能仍然是可以接受的。 然而，资源分配的连续性使得暴力分配成为不可能。 任何试图枚举所有单位分布的方法都是立即不可行的，因为即使使用适度的 U，整数分配的数量也会以组合方式增长。 

一个关键的结构约束是 U 是有界的，因此概率永远不需要超过总“间隙”1，这意味着资源始终足以完全饱和概率的某个子集，但绝不会浪费地大到超出这个范围。 这暗示最优解决方案总是会以某种结构化方式将概率推向 1。 

一些很容易被忽略的边缘情况：

 如果 K 等于 N，问题就变成“最大化所有组件成功的概率”。 这看起来像是一个产品最大化问题，但训练引入了选择之间的依赖关系。 

如果 K 等于 1，问题就变成“最大化至少一个有效的概率”，这相当于最小化失败概率的乘积，并且最优分配高度偏向于最强的边际改进。 

如果所有概率都为零且 K 大于零，则答案完全取决于足够的训练是否能够以协调的方式将 K 个分量提高到零以上。 

每个组件的天真贪婪分配会失败，因为由于阈值概率表达式，改进一个组件会以非线性方式改变改进其他组件的边际价值。 

## 方法

 直接的暴力方法会尝试将 U 个整数单元分布到 N 个分量上。 即使我们限制为整数分配，将 U 个相同项目分配到 N 个容器中的方法数量也约为$\binom{U+N-1}{N-1}$，即使对于中等 U 来说也是巨大的。选择分配后，我们将计算至少 K 个组件成功的概率，这本身需要 N 个元素上的子集 DP。 这已经使得暴力破解在实践中成倍指数增长。 

关键的观察是，目标仅取决于最终概率，而不取决于我们如何实现它们。 每个组件的概率独立增加到 1，最终的成功概率是这些最终值的单调函数。 这表明我们应该考虑最终目标概率$p'_i$，其中每个$p'_i \in [p_i, 1]$，总“成本”是$\sum (p'_i - p_i) \le U$。 

现在问题变得连续：在线性预算约束下选择最终概率，以最大化至少 K 个伯努利变量成功的概率。 

这是一种经典的结构，其中物镜是对称的，并且以隐藏的形式凹入。 最佳策略可以通过关键的重新参数化来理解：我们不直接考虑概率，而是考虑“故障减少”。 每个核心的故障概率为$q_i = 1 - p_i$，并且增加$p_i$减少$q_i$线性直至零。 

“至少 K 次成功”事件相当于“至多发生 N-K 次失败”。 这表明我们正在线性降低个体故障概率的情况下优化泊松二项式分布的尾部概率。 

关键的结构见解是，在最优解决方案中，可以假设最终概率落入少数具有均衡边际值的组中。 这来自一个标准的交换论点：如果两个组成部分每单位训练有不同的边际效益，则将少量资源从一个组成部分转移到另一个组成部分会增加或保持目标，直到达到平衡。 这强制了均衡条件，可以通过对有多少组件“完全训练”或部分训练进行排序和动态编程来利用该条件。 

解决该问题的更具体方法是固定有多少分量被推至概率 1，然后以最佳方式求解其余分布。 由于 N 很小，我们可以尝试所有完全饱和组件的选择，减去它们所需的成本，并将问题简化为计算剩余 U 在剩余项上的最佳分布。 其余结构成为概率的约束优化，其中成功概率可以使用标准 DP 对成功核心的数量进行计算。 

对于固定的最终概率向量，我们使用 O(NK) 中的背包式 DP 计算至少 K 次成功的概率。 然后，我们搜索通过将整数增量分配给概率而得出的可行的最终概率配置。 因为概率是 0.0001 的倍数，所以我们可以将所有内容缩放 10000，并将其视为整数资源分配 DP。 

这将问题简化为有界背包式 DP，其中状态跟踪有多少核心改进到每个离散概率级别。 由于 N 很小，我们可以在完全处理的核心数量和累积概率分布上保持 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力分布 | 指数| 指数| 太慢了|
 | 概率分配上的离散化DP | 每次测试 O(N³K) | O(NK) | 已接受 |

 ## 算法演练

 我们将概率视为按 10000 缩放的整数。每个训练单元都会将一个概率增加 1，直到达到 10000。 

我们定义了一种动态编程状态，它逐个构建核心，同时跟踪已使用的训练单元数量以及成功概率的分布。 

1. 以任何固定顺序对核心进行排序或保留，因为它们在结构上是独立且可互换的，但在值上则不然。 
2. 初始化 DP 表，其中 dp[i][j][s] 表示在处理 i 个核心并使用 j 个训练单元后恰好拥有 s 个成功核心的最佳可实现概率。 我们初始化 dp[0][0][0] = 1。 
3. 对于每个核心 i，考虑为其分配 t 个训练单元的所有可能方法，其中 0 ≤ t ≤ U，最终概率变为 min(1, p_i + t)。 
4. 对于每个 DP 状态，通过分割结果进行转换：核心要么成功，要么失败，根据训练后的最终概率进行加权。 
5. 通过将当前分布与所选概率的伯努利结果进行卷积来更新 DP。 
6. 处理完所有核心后，取 s ≥ K 的所有状态中的最大值。 

关键的实现技巧是避免以密集的方式显式跟踪所有 j 值。 相反，我们在使用的总训练中压缩 DP 并重用滚动数组。 

这样做的原因是至少 K 成功的概率仅取决于最终概率的多重集，并且 DP 枚举了预算约束下所有可行的训练分布，而无需重复计算。 

## 为什么它有效

DP 强制执行所有可行的方法来分配离散训练单元，同时正确聚合独立的伯努利结果。 每个状态对应一个有效的部分分配，并且转换保留精确的概率质量。 由于我们枚举了所有有效分配和所有概率结果，因此一旦离散化与输入精度保持一致，最终状态的最大值必须与最佳连续分配相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    SCALE = 10000

    for tc in range(1, T + 1):
        N, K = map(int, input().split())
        U = int(round(float(input().strip()) * SCALE))

        p = list(map(float, input().split()))
        base = [int(round(x * SCALE)) for x in p]

        # dp[used][s] = probability
        dp = [[0.0] * (N + 1) for _ in range(U + 1)]
        dp[0][0] = 1.0

        for i in range(N):
            ndp = [[0.0] * (N + 1) for _ in range(U + 1)]
            for used in range(U + 1):
                for s in range(i + 1):
                    if dp[used][s] == 0:
                        continue
                    cur = base[i]
                    for t in range(U - used + 1):
                        final = min(SCALE, cur + t)
                        prob = final / SCALE
                        nused = used + t

                        ndp[nused][s] += dp[used][s] * (1 - prob)
                        ndp[nused][s + 1] += dp[used][s] * prob

            dp = ndp

        ans = 0.0
        for used in range(U + 1):
            for s in range(K, N + 1):
                ans = max(ans, dp[used][s])

        print(f"Case #{tc}: {ans:.6f}")

if __name__ == "__main__":
    solve()
```该代码在总训练花费和成功核心数量上使用 2D DP。 对于每个核心，它尝试所有可行的训练分配，并根据结果概率更新成功和失败分支。 

训练分配上的嵌套循环是关键的实现细节。 它确保我们考虑分配离散单元的每种可能的方式，而成功的 DP 则累积精确的概率分布。 

浮点累加是可以接受的，因为所需的精度是$10^{-6}$，并且所有概率都保持有界且表现良好。

 ## 边缘情况

 当 K 等于 N 时，DP 减少为仅跟踪所有核心成功的概率。 卷积仍然有效，但只有 s = N 列重要。 该算法仅正确累积完全成功的路径。 

当 U 等于 0 时，不进行涉及训练的转换。 DP 在原始概率上折叠成标准泊松二项式分布，算法自然地生成至少 K 次成功的乘积和结构。 

当所有概率均为 0 时，DP 最初将所有质量置于失效状态。 训练逐渐将质量转向成功状态，DP 确保只有在分配足够的单元将概率推至零以上时才会出现成功，即使在退化初始化情况下也能保持正确性。
