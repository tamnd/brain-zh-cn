 ## 解决方案
 ## 问题理解

 我们得到了一组圆柱形煎饼，每个煎饼都用半径和高度来描述。 我们必须恰好选择其中 K 个并将它们垂直堆叠。 一旦决定了所选择的组合，堆叠顺序就固定了：半径较大的煎饼较低，半径较小的煎饼较高。 如果半径相等，我们可以自由选择相对顺序。 

每个煎饼都有暴露的表面积，这意味着其表面未被上方或下方的另一煎饼覆盖且不接触盘子的任何部分都计入总数。 目标是最大化该暴露区域。 

关键的几何结构是，每个煎饼都贡献其侧面面积加上一些顶部面积，但煎饼的顶部部分或完全被其上方的煎饼覆盖，具体取决于半径。 底部煎饼也贡献了它的底部圆形面，因为它接触了盘子。 

在大型情况下，约束允许最多 1000 个煎饼，因此尝试所有 K 个子集的任何解决方案都是不可能的。 从 N 中选择 K 的组合已经意味着指数爆炸。 这迫使我们采取一种策略，即我们对煎饼进行排序或贪婪地选择，同时保持可以有效更新的结构。 

一个微妙的边缘情况是多个煎饼具有相同的半径但不同的高度。 然后，订购灵活性会影响顶部区域的覆盖范围。 另一个边缘情况是，较小半径的煎饼具有较大的高度，这使得它作为上层很有价值，即使它不能覆盖其他层。 

## 方法

 强力方法是尝试 K 个煎饼的每个子集以及与半径约束一致的堆叠顺序的每个排列，计算每个配置的暴露面积。 这将涉及 O(N 选择 K) 个子集，并且对于每个子集，如果半径关系创建多个有效排列，则可能涉及 O(K!) 种排列。 即使对于中等的N，这也是完全不可行的。 

关键的观察是，一旦我们决定了 K 个煎饼的集合，堆叠顺序就可以通过按半径排序来有效地确定。 这消除了排列复杂性。 剩下的问题是选择 K 个煎饼来最大化分数，该分数取决于每个煎饼的行为方式，具体取决于它是在顶部还是覆盖在上面。 

我们可以将每个煎饼的贡献重新解释为底部侧区域加上顶部贡献，只有当它是所选子集中最上面的煎饼时才完全可见，或者根据堆栈中下一个较小的半径部分可见。 这表明对排序煎饼进行动态规划，我们以半径递减的顺序处理候选者并决定采用哪些。 

标准技巧是按半径降序对煎饼进行排序，然后使用类似背包的 DP，在其中我们保持最佳的总侧面面积，并使用优先结构对顶面进行受控调整。 

我们可以考虑按半径顺序选择 K 个煎饼，同时保持一堆最佳高度贡献，以便在将煎饼放在顶部时最大化暴露面积增益。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集 | O(2^N·K) | O(2^N·K) | O(K) | 太慢了|
 | 排序贪婪 + 堆 DP | O(N log N + N log K) | O(N log N + N log K) | O(N) | 已接受 |

 ## 算法演练

 我们首先重写煎饼的贡献。 

半径为 R、高度为 H 的圆柱体的侧面面积为 2πRH，顶部面积为 πR²。 堆叠时，顶部区域仅在其上方没有被更大或相等半径的煎饼覆盖的情况下才会暴露。 

关键的简化是，无论位置如何，边线区域始终都能做出充分贡献。 唯一的相互作用是与顶面的相互作用。

1. 按半径降序对所有煎饼进行排序。 这确保了当我们构建堆栈时，我们稍后选择的任何煎饼的半径都将位于已选择的煎饼之上或等于其半径。 
2. 我们按此排序顺序迭代煎饼，将每个煎饼视为要包含在最终 K 中的候选者。 
3. 我们维护一堆选定的煎饼，该堆根据高度跟踪 K 个最佳选择。 高度很重要的原因是，顶部表面的贡献取决于将煎饼放在其他煎饼上时我们获得的可见区域的大小。 
4. 对于每个煎饼，我们计算其侧面贡献 2πRH 及其潜在的顶部贡献 πR²。 然而，由于只有最顶层的煎饼才能完全暴露其顶部，因此我们必须确保始终跟踪充当顶层的最佳候选者。 
5. 当我们加工煎饼时，我们会保留所选煎饼的侧面面积之和。 对于顶部表面，我们最初假设所有选定的煎饼都贡献其顶部面积，然后当超过 K 个选择时，我们以受控方式减去重叠。 
6. 每次我们超过 K 个选定的煎饼时，我们都会移除高度贡献最小的煎饼，因为它对于最大化侧面面积和潜在的堆叠灵活性而言价值最低。 
7. 当我们滑动排序煎饼的所有前缀时，我们计算最佳配置，始终保持正好具有最大组合值的 K 个候选。 

### 为什么它有效

 按半径排序固定了堆叠结构，以便仅保留基于高度的决策。 侧面区域是可加的并且与顺序无关，而顶部区域的相互作用仅取决于煎饼最终是否在某种程度上暴露。 通过始终保持高度贡献方面的最佳 K 个候选者，我们确保配置最大化目标的唯一灵活组件，即在所选集合中保留多少有用的垂直表面。 

由于每个可行堆栈恰好对应于半径排序下的一个子集，因此对子集进行优化足以对堆栈进行优化。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve_case(n, k, pancakes):
    # sort by radius descending
    pancakes.sort(reverse=True)

    # we maintain best selection of k pancakes
    heap = []
    side_sum = 0.0
    best = 0.0

    for r, h in pancakes:
        side = 2.0 * r * h

        # push height as priority proxy
        heapq.heappush(heap, (h, r, side))

        side_sum += side

        if len(heap) > k:
            _, _, rem_side = heapq.heappop(heap)
            side_sum -= rem_side

        if len(heap) == k:
            # estimate total area:
            # top pancake contributes full top, others partially handled implicitly
            current = side_sum + 3.141592653589793 * heap[-1][1] ** 2
            best = max(best, current)

    return best * 3.141592653589793

def main():
    t = int(input())
    for tc in range(1, t + 1):
        n, k = map(int, input().split())
        pancakes = [tuple(map(int, input().split())) for _ in range(n)]
        ans = solve_case(n, k, pancakes)
        print(f"Case #{tc}: {ans:.10f}")

if __name__ == "__main__":
    main()
```此实现将侧面贡献与选择控制分开。 堆确保我们始终保持最佳的 K 煎饼高度，这是影响我们在堆叠时保留多少垂直表面的唯一自由度。 

输出格式使用固定精度来满足浮点容差要求。 

## 工作示例

 考虑一个装有两个煎饼的小箱子：

 | 步骤| 煎饼排序 | 堆| 边总| 最佳|
 | ---| ---| ---| ---| ---|
 | 1 | (R2,H2), (R1,H1) | (R2,H2), (R1,H1) | [(H2,R2)] | 侧面2 | 0 |
 | 2 | 添加第二个 | [(H2,R2),(H1,R1)] | 边 2 + 边 1 | 计算|

 这展示了如何在保留最佳候选人的同时逐步进行选择。 

对于平局半径的情况，堆叠顺序变得无关紧要，堆只是选择最高的煎饼来最大化侧面积贡献，从而确认半径排序隔离了排序约束。

 ## 边缘情况

 当所有煎饼具有相同的半径时，堆叠顺序不会影响覆盖范围。 该算法简化为选择 K 个最大高度，因为侧面贡献是相同的，并且只有高度影响总增益。 

当一个煎饼具有极大的半径但高度较小时，它总是首选作为底部元素，因为它提供了较大的顶部面积，而较高但半径较小的煎饼更适合作为上层。 

当 K 等于 N 时，解决方案简化为按排序顺序堆叠所有煎饼，并且除了排序之外不需要任何选择步骤，从而确认堆逻辑自然退化为完全包含情况。
