 ## 解决方案
 ## 问题理解

 我们有一棵树，根在顶点`1`。 在这棵有根树上玩游戏，直到每个节点都消失。 

每次移动时，都会随机均匀地选择当前剩余的顶点之一。 当一个顶点`v`被选择时，整个子树的根为`v`立即删除，包括`v`本身。 当根最终被删除时，游戏结束，因为删除根会删除整个剩余的树。 

任务是计算树变空之前的预期移动次数。 

输入描述了一个无向树，最多可达`10^5`顶点。 由于树的根位于顶点`1`，我们可以从根开始进行 DFS 或 BFS 之后用父子关系来解释每条边。 

约束条件`n ≤ 100000`立即排除任何明确模拟随机过程的方法。 甚至一个`O(n^2)`算法需要大约`10^10`在最坏的情况下进行操作，远远超出了时间限制。 我们需要一个线性或接近线性的解决方案。 

问题的一个微妙方面是游戏的状态在每次删除后都会发生变化。 选择顶点的概率取决于哪些顶点在先前的移动中幸存下来。 尝试在所有可能的剩余树之间编写转换很快就变得不可能。 

考虑一条链：```
1
|
2
|
3
```一个常见的错误是认为每个顶点都是独立贡献的。 事实并非如此。 如果顶点`2`被选择，顶点`3`没有被选中就消失了。 任何为每个被选择一次的顶点分配固定概率的方法都会产生错误的期望。 

另一个容易的陷阱是忘记最终总是选择根。 对于单节点树：```
1
```游戏总是只持续一步，所以答案是`1`。 任何给出的公式`0`这里缺少根的贡献。 

星形树也暴露了错误的推理：```
1
/|\
2 3 4
```叶子只有被自己选择才能消失，而根则立刻毁灭一切。 预期答案不等于树高、叶子数量或任何其他明显的结构量。 

关键是找到一个可以直接计算其期望值而无需对整个过程进行建模的量。 

## 方法

 暴力解决方案会将所有可能的剩余树视为一个状态。 来自包含`k`顶点，每个顶点都是以概率选择的`1/k`，导致通过删除子树获得另一个状态。 

这个状态空间视图是正确的，因为它完全符合游戏规则。 不幸的是，即使是小树也会产生指数级的许多可能的剩余配置。 一棵树与`10^5`顶点使得这完全不可行。 

突破来自于改变我们的衡量标准。 

不要直接询问预期的移动次数，而是考虑特定顶点是否为游戏贡献了一步。 

想象一下为每个顶点分配一个随机优先级。 在每一步选择均匀随机的剩余顶点相当于生成所有顶点的随机排列并按该顺序显示它们。 当且仅当一个顶点出现在排列中该顶点的每个祖先之前时，它实际上会引起移动。 

为什么？ 如果祖先首先出现，则该祖先的子树删除会在顶点被选择之前删除该顶点。 如果该顶点是从根到自身的路径上所有顶点中最早的，那么它会存活到轮到它并贡献一步。 

对于深度处的顶点`d`（根深`1`），从根到该顶点的路径恰好包含`d`顶点。 其中`d`顶点，每个顶点都有可能成为随机排列中最早的顶点。 因此$$P(\text{vertex } v \text{ contributes a move}) = \frac{1}{d}.$$让`I(v)`是顶点的指示器`v`贡献一个动作。 总移动次数为$$X = \sum_v I(v).$$利用期望的线性，$$E[X] = \sum_v E[I(v)] = \sum_v \frac{1}{\text{depth}(v)}.$$问题就变得极其简单了。 我们只需要有根树中每个顶点的深度。 

单个 DFS 计算所有深度，答案是它们的倒数之和。

 | --- | --- | --- | --- |
 | 暴力状态枚举| 指数| 指数| 太慢了 |
 | DFS深度求和| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 构建树的邻接表。 
2. 在顶点处建立树根`1`。 
3. 从根执行 DFS 并使用深度计算每个顶点的深度`1`为根。 
4. 对于每个访问过的顶点，添加`1 / depth`到答案。 
5. 继续，直到访问完所有顶点。 
6. 以足够的精度打印累加和。 

不明显的部分是步骤 4。当一个顶点是随机排列解释中其根到顶点路径上最早的顶点时，它就贡献一次移动。 由于该路径上的每个顶点都有可能是最早的，因此贡献概率就是`1 / depth`。 

### 为什么它有效

 对于任意顶点`v`，定义一个指标随机变量：$$I(v)= \begin{cases} 1,&\text{if }v\text{ is ever selected},\\ 0,&\text{otherwise}. \end{cases}$$顶点`v`被选择当且仅当没有祖先`v`在它之前被选择。 在所有顶点的随机排列中，这种情况恰好发生在`v`是根到的第一个顶点`v`小路。 
路径包含`depth(v)`顶点，对称性给出$$P(I(v)=1)=\frac{1}{depth(v)}.$$游戏总步数等于$$X=\sum_v I(v).$$应用期望的线性，$$E[X] = \sum_v E[I(v)] = \sum_v P(I(v)=1) = \sum_v \frac{1}{depth(v)}.$$DFS 对每个深度只计算一次，因此该算法精确地计算该公式。 由于该公式等于预期的移动次数，因此该算法是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    ans = 0.0

    stack = [(1, 0, 1)]  # node, parent, depth

    while stack:
        u, parent, depth = stack.pop()

        ans += 1.0 / depth

        for v in g[u]:
            if v != parent:
                stack.append((v, u, depth + 1))

    print("{:.15f}".format(ans))

if __name__ == "__main__":
    solve()
```邻接表将树存储在`O(n)`记忆。 

DFS 是迭代实现的，而不是递归实现的。 长度路径上的递归 DFS`100000`会超出Python的递归限制。 使用显式堆栈可以完全避免该问题。 

每个堆栈条目都存储当前顶点、其父顶点及其深度。 当一个顶点被弹出时，我们立即添加`1/depth`到答案。 这直接实现了经过验证的公式$$\sum_v \frac{1}{depth(v)}.$$根从深处开始`1`， 不是`0`。 这很重要，因为与根相关的概率是`1`，除以零显然是无效的。 

答案累积在浮点变量中。 双精度足以满足所需`10^{-6}`准确性。

 ### 单顶点树

1
```DFS 仅访问根。 

| 顶点| 深度 | 贡献|

 回答：$$1$$这证实了根总是贡献一步，并且深度必须从`1`。 

### 长链

 输入：```

1 2
2 3

```深度是`1, 2, 3, 4`。 

答案就变成了$$1+\frac12+\frac13+\frac14 = 2.083333333333333.$$递归 DFS 可能会在长度链上溢出`100000`，但迭代堆栈可以安全地处理它。 

### 星形以根为中心

 输入：```
4
1 2
1 3
1 4
```深度是`1, 2, 2, 2`。 

答案是$$1+\frac12+\frac12+\frac12 = 2.5.$$此案例验证了每个叶子通过其概率独立做出贡献`1/2`，即使选择根会立即删除所有叶子。 

### 不平衡树

 输入：```
5
1 2
2 3
1 4
4 5
```深度为：

 | 顶点| 深度 |
 | --- | --- |
 | 1 | 1 |
