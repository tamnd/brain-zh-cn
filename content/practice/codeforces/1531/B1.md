 ## 问题理解

 我们得到了一组监视器，每个监视器都有一个宽度和一个高度。 我们想要计算有多少对不同的无序显示器可以旋转，以便它们的高度匹配。 旋转显示器会交换其宽度和高度。 目标是找到所有对$(i, j)$这样，在可能旋转其中一个或两个之后，监视器具有相同的垂直高度。 

输入尺寸$n$可以达到 1000。这足够小，以至于$O(n^2)$解决方案是可行的，因为$n^2 = 10^6$操作，完全符合典型的 1-2 秒限制。 高度和宽度值可以非常大（$10^9$），因此任何尝试创建按维度索引的数组的方法都是不可能的。 

宽度等于高度的方形显示器会出现微妙的边缘情况。 例如，如果我们有监视器$(2, 2)$和$(2, 2)$，任何旋转都会使高度保持不变。 同样，如果两个显示器有尺寸$(2, 3)$和$(3, 2)$，旋转第一个并保持第二个不变，将它们的高度对齐为 3。仅检查原始方向的简单实现会错过这种可能性。 

另一个边缘情况是多个相同的显示器。 如果我们有三个尺寸的显示器$(3, 5)$，算法必须正确计算所有无序对，而不仅仅是它遇到的第一个组合。 

## 方法

 蛮力方法迭代所有无序对。 对于每一对，我们检查四种可能性：保持两者不变、旋转第一个、旋转第二个或旋转两者。 如果这些组合中的任何一个导致相同的高度，我们就会增加计数。 这是正确的，因为它明确地检查每个有效的配对。 支票数量为$4 \times \frac{n(n-1)}{2}$，即$O(n^2)$并为$n \le 1000$。 

让我们简化问题的观察是，我们只关心每个显示器可以贡献的可能高度集：其原始高度或旋转后的宽度。 对于每个监视器，我们可以存储一个排序的元组$(\min(w, h), \max(w, h))$。 如果两个监视器的可能高度之间存在任何交集，则它们可以形成有效的对。 检查具有此属性的所有对也是$O(n^2)$，但比显式枚举旋转稍微干净一些。 

我们可以尝试基于频率的方法，计算支持每个高度的显示器数量，然后进行组合求和。 这最适合解决非常大的问题$n$或高度范围受限。 为了$n \le 1000$， 这$O(n^2)$方法简单、清晰且足够快。

 ## 算法演练

 1.读取显示器数量$n$。 
2. 读取每个显示器的宽度和高度，并将它们作为元组存储在列表中。 
3. 初始化计数器`count = 0`对于有效的对。 
4. 循环所有对$(i, j)$和$i < j$。 对于每一对，提取宽度和高度$(w_i, h_i)$和$(w_j, h_j)$。 
5. 检查所有四种方向组合：$(h_i == h_j)$,$(w_i == h_j)$,$(h_i == w_j)$， 和$(w_i == w_j)$。 如果有匹配，则递增`count`。 
6. 检查完所有对后，打印`count`。 

为什么它有效：不变的是我们只计算对一次，因为$i < j$。 对于每一对，我们都会考虑所有旋转，因此不会错过任何有效组合。 我们从不重复计算，因为每个无序对都只被考虑一次。
