 ## 解决方案
 ## 问题理解

 我们从一个正整数数组开始。 我们必须将一个元素更改为不同的值，仍然在`1`和`10^9`。 在单次替换之后，我们按非降序对数组进行排序。 

任务是在执行一次替换后生成字典顺序最小的可能排序数组。 

原始语句中关于“每个位置的最小可能值”的措辞是描述字典顺序最小排序数组的另一种方式。 我们希望第一个位置尽可能小，然后是第二个，依此类推。 

约束条件`n ≤ 10^5`立即排除任何二次方。 即使是一个简单的`O(n^2)`算法需要大约`10^10`最坏情况下的操作，远远超出了极限。 这里排序足够便宜，因为`O(n log n)`为了`10^5`元素在 Python 中很容易管理。 

棘手的部分是了解什么替换实际上会产生最小的最终排序数组。 

假设数组已经排序：```
1 2 3 4 5
```如果我们替换最大值`5`和`1`，我们得到：```
1 1 2 3 4
```这显然是最佳的，因为使数字更小有助于尽早排序。 

现在考虑一个数组，其中每个元素都已经`1`:```
1 1 1
```我们被迫将一种元素改变为不同的东西。 我们无法取代`1`与另一个`1`。 最好的选择是最少地增加一个元素：```
1 1 2
```粗心的实现可能仍然会尝试用以下内容替换某些内容`1`，产生未更改的数组，这是非法的。 

另一个微妙的情况是当数组包含多个最小值但也包含更大的数字时：```
1 1 5
```正确答案是：```
1 1 1
```我们替换`5`和`1`。 天真的“总是增加一个值”策略会忽略我们仍然可以使数组总体更小。 

真正的区别是数组是否已经完全由`1`s`。 

## 方法

 蛮力的想法很简单。 对于每个位置，尝试用每个可能重要的候选值替换该元素，对结果数组进行排序，并保留按字典顺序排列的最小答案。 

这在概念上是有效的，因为问题直接要求最小可能的最终排序数组。 如果我们枚举每个有效的替换，其中一个必定是最优的。 

问题在于可能性的数量。 即使我们只尝试一小组候选替换值，对大小的数组进行排序`n`每个职位已经成本`O(n^2 log n)`。 和`n = 10^5`，这是完全不可行的。 

关键的观察是，只有尽可能小的替代价值才重要。 

如果数组包含任何大于`1`，然后将其中一个值替换为`1`严格改进排序数组。 在所有选择中，替换最大元素是最好的，因为它删除了最大的数字，同时添加了允许的最小数字。 

例如：```
1 2 3 4 5
```变成：```
1 1 2 3 4
```更换后`5`和`1`。 

该策略唯一失败的时候是每个元素都已经相等的时候`1`。 那么我们就不能用任何东西来替换`1`，因为该值实际上必须改变。 最小的有效修改是替换一个`1`和`2`。 

所以最优策略变得很小：

 1. 对数组进行排序。 
2. 如果所有元素都是`1`，将最后一项改为`2`。 
3. 否则，将最大元素更改为`1`。 
4. 如有必要，再次排序。 

因为数组已经排序，所以最终的排列是立即的。

 | --- | --- | --- | --- |
 | 蛮力 | O(n² log n) 或更糟 | O(n) | 太慢了|
 | 最佳| O(n log n) | O(n log n) | O(1) 额外，不包括排序 | 已接受 |

 ## 算法演练

 1.读取数组并按非降序排序。 

排序让我们可以直接推断字典顺序。 最小的元素首先出现，因此改进较早的位置变得显而易见。 
2. 检查最大元素是否等于`1`。 

由于数组已排序，因此此条件意味着每个元素都是`1`。 
3. 如果所有元素都是`1`，将最后一个元素替换为`2`。 

我们必须恰好修改一个值，并且`2`是不同于以下的最小有效数`1`。 
4. 否则，将当前最大的最后一个元素替换为`1`。 

这会删除最大值并插入尽可能小的值，从而生成按字典顺序排列的最小排序数组。 
5. 如果需要，再次对数组进行排序，或者直接打印修改后的排序顺序。 

将最大元素替换为后`1`，新的`1`属于前面。 执行另一种排序很简单并且仍然足够高效。 

### 为什么它有效

 字典顺序由最早的不同位置决定。 为了最小化最终的排序数组，我们希望在开始时有尽可能多的小值。 

如果数组包含某个值大于`1`，将这样一个值替换为`1`增加最小元素的数量并删除较大数量的元素。 替换最大值始终至少与替换任何较小的值一样好，因为排序后的前缀保​​持不变，而后面的位置会变小。 

如果每个元素都已经`1`，减少任何值都是不可能的。 最小的法律变化只是增加了一个元素`2`，给出所有有效修改中可能的最小排序结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

a.sort()

if a[-1] == 1:
    a[-1] = 2
else:
    a[-1] = 1

a.sort()

print(*a)
```解决方案首先对数组进行排序。 这使得最大元素很容易访问`a[-1]`。 

条件`a[-1] == 1`足以确定是否所有元素都`1`，因为数组已排序。 如果最大值是`1`，那么每个值也必须是`1`。 

当所有元素都为`1`，我们将最后一个元素替换为`2`。 选择任何更大的数字都会产生字典顺序更差的数组。 

否则，我们将最大元素替换为`1`。 这会在删除现有最大数字的同时引入另一个最小值。 

最终排序恢复非降序。 它的成本仍然可以接受，因为排序`10^5`整数两次很容易在限制之内。 

一个常见的错误是忘记替换实际上必须改变值。 对于全一数组，替换`1`与另一个`1`无效。 

另一个简单的错误是替换最小的非一个元素而不是最大的元素。 这会在数组中留下更大的数字，并产生更差的词典结果。

## 测试用例```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    if a[-1] == 1:
        a[-1] = 2
    else:
        a[-1] = 1

    a.sort()

    print(*a)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("5\n1 2 3 4 5\n") == "1 1 2 3 4\n", "sample 1"

# minimum size
assert run("1\n1\n") == "2\n", "single element equal to 1"

# single non-one element
assert run("1\n7\n") == "1\n", "replace maximum with 1"

# all equal values
assert run("4\n1 1 1 1\n") == "1 1 1 2\n", "all ones case"

# mixed values
assert run("5\n1 1 5 7 9\n") == "1 1 1 5 7\n", "replace largest value"

# already sorted but with duplicates
assert run("6\n2 2 2 2 2 2\n") == "1 2 2 2 2 2\n", "duplicate non-one values"

 ## 边缘情况

 考虑输入：```
1
1
```排序后的数组仍然是`[1]`。 由于每个元素都等于`1`，替换为`1`是非法的，因为值必须改变。 该算法将唯一的元素更改为`2`，生产：```
2
```现在考虑：```
3
1 1 5
```排序后，数组为：```
1 1 5
```最大值不是`1`，因此该算法替换为`5`和`1`:```
1 1 1
```这是最佳的，因为与任何其他有效答案相比，第一个不同的位置变得尽可能小。 

另一个棘手的情况是：```
4
2 2 2 2
```该算法替换最大的`2`和`1`:```
1 2 2 2
```替换任何其他元素在排序后会得到相同的多重集，因此选择最后一个元素就足够了。 

最后，考虑：```
5
1 1 1 1 1000000000
```该算法将巨大的值替换为`1`，生产：```
1 1 1 1 1
```这证实了移除值的实际大小并不重要。 任何大于的值`1`应该成为`1`，并删除最大值给出最好的词典结果。
