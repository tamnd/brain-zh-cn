 ## 解决方案
 ## 问题理解

 游戏开始时，Ricardo 的余额为 100 sbec。 这些盒子是按固定顺序排列的，他可以打开其中的一些前缀。 打开盒子后，其隐藏值将添加到当前余额中。 他可以随时停下来拿走当前的金额，包括在打开任何盒子之前。 

任务是通过选择最佳停止点来找到可实现的最大平衡。 由于精确打开前 k 个框会得到 100 加上这些 k 值之和的余额，因此该问题相当于找到最佳前缀和，同时也允许空前缀。 

输入包含框的数量，后面按顺序包含每个框内的值。 输出是里卡多可以获得的最大最终余额。 

框的数量最多为 100 个，每个值都在 -1000 到 1000 之间。这些限制足够小，即使是简单的线性处理也绰绰有余。 对于这个特定的界限，二次方法仍然可以通过，但问题的结构给出了直接的一次性解决方案。 不需要复杂的数据结构，因为每个盒子仅通过当前累积余额影响未来的选择。 

主要边缘情况是每个框都为负的序列。 粗心的实施可能会假设里卡多必须打开至少一个盒子并返回破坏性最小的损失。 例如：```
3
-5
-2
-8
```正确的输出是`100`，因为里卡多可以立即退出。 仅检查非空前缀的方法将错误地返回`95`。 

另一个边缘情况是最佳答案出现在几个否定框之后。 例如：```
4
-10
-10
30
-100
```正确的输出是`110`，因为打开前三个框的净增益为 10。只要当前总和变为负数就停止的方法将会失败，因为它会丢弃稍后变得有利可图的前缀。 

## 方法

 直接的暴力解决方案将模拟每一个可能的决策。 由于里卡多可以在打开任意数量的盒子后停止，因此我们可以尝试每个可能的停止位置，计算该点的余额，并保留最大值。 有 C+1 个可能的停止位置，包括立即停止。 如果每个人从头开始重新计算前缀和，则总工作量为 O(C²)。 当 C = 100 时，这是可以接受的，但它忽略了这样一个事实：每个连续的停止位置几乎与前一个停止位置共享其所有信息。 

有用的观察结果是，在方框中移动时唯一变化的值是当前余额。 打开下一个盒子后，新余额就是旧余额加上该盒子的值。 我们可以扫描一次盒子，更新当前余额并记住迄今为止看到的最大值。 这是有效的，因为每一种可能的最终状态都与本次扫描期间的一个点完全对应。 

暴力方法之所以有效，是因为会检查每个可能的停止选择，但它会多次重复相同的前缀计算。 观察到每个下一个选择的不同之处仅在于添加一个新值，从而将问题简化为单遍。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(C²) | O(1) | O(1) | 接受给定的限制，但没有必要 |
 | 最佳| O(C)| O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从当前余额等于 100 开始，答案等于 100。初始答案代表在打开任何框之前退出的选项。 
2. 按顺序读取每个框的值并将其添加到当前余额中。 当前余额现在代表里卡多在打开此盒子后停止时将收到的金额。 
3. 将当前余额与目前找到的最佳答案进行比较，保留较大的值。 在扫描过程中，每个停止位置都会被考虑一次。 
4. 处理完所有盒子后，输出存储的最大余额。 

为什么它有效：

 处理完前 i 个盒子后，当前余额正是里卡多打开这些 i 个盒子后所拥有的金额。 该算法存储从 0 到 i 的所有停止点之间的最大平衡。 当处理下一个框时，新的停止点将添加到这组可能性中，并且如果需要，则更新最大值。 当所有盒子都被处理时，所有可能的策略都已被考虑，因此存储的答案是最佳的最终平衡。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    c = int(input())
    balance = 100
    answer = 100

    for _ in range(c):
        balance += int(input())
        if balance > answer:
            answer = balance

    print(answer)

if __name__ == "__main__":
    solve()
```变量`balance`存储里卡多如果继续打开箱子直到当前位置将会拥有的数量。 它从 100 开始，因为选择零个框是一个有效的策略。 

变量`answer`存储迄今为止所有停止点中的最佳平衡。 将其初始化为 100 可以处理每个盒子都是有害的并且 Ricardo 永远不应该打开一个盒子的情况。 

该循环只处理每个框一次。 更新发生在与比较之前`answer`，因为打开当前框会创建一个新的可能的停止点。 Python 整数在给定限制下不会溢出，因此不需要特殊处理。 

不涉及索引，这避免了差一错误。 该算法自然会处理最后一个框，因为它会在每次添加后立即检查余额。

 ## 边缘情况

 对于全否定的情况：```
3
-5
-2
-8
```该算法开始于`balance = 100`和`answer = 100`。 每次相加后，余额分别变为 95、93 和 85。这些值都不会改善答案，因此最终结果仍为 100。这符合在打开任何盒子之前退出的策略。 

对于暂时不好的前缀成为最佳选择的情况：```
4
-10
-10
30
-100
```扫描期间的余额为 90、80、110 和 10。算法保留最大看到的值，因此当第三个框后达到 110 时，该值即为答案。 最后的否定框无法消除这样一个事实：提前停止已经是一个有效的选择。 

对于最小尺寸输入：```
1

```该算法根据初始选项 100 检查唯一可能的打开盒子结果 50。最终答案是 100，确认不需要打开单个有害盒子。
