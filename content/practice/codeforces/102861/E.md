 ## 解决方案
 ## 问题理解

 员工是一棵有根的树，公司老板是根。 每个员工的年龄都不会大于其经理的年龄，因此当职位向下移动时，年龄永远不会增加。 

一方由其所有者和允许的年龄间隔来描述。 所有者对于自己的一方始终有效。 对于要参加的其他员工，他们必须与已经参加的人员有直接联系，并且他们的年龄必须在该区间内。 这意味着在删除年龄超出该区间的员工后，被邀请的员工正是树内所有者的连通组件。 

对于每个员工，我们需要计算有多少个聚会间隔产生了包含该员工的连接组件。 

限制很大：员工和参与方的数量都可以达到 100000。一个为每个参与方探索树的解决方案在最坏的情况下可以执行大约 10^10 次操作，这远远超出了可能的范围。 我们需要一个接近 O((N + M) log N) 的解决方案。 

年龄排序给出了关键结构。 当一方有所有者时`o`和最大年龄`R`，我们可以从`o`而经理的年龄最多还是`R`。 让最高可达的员工成为`h`。 然后，受邀参加聚会的每个员工都位于`h`，因为每个祖先`o`最多`h`是有效的，并且来自这些祖先的每个侧分支也保持连接。 在该子树中，唯一剩下的限制是最小年龄`L`。 

在某些情况下，实施可能会失败。 

考虑一个作为公司根的所有者：```
1 1
5 1
1 1 5
```答案是：```
1
```假设每个员工都有一个与自己不同的父母的解决方案在攀登祖先时可能会失败。 

另一种情况是员工有确切的年龄界限：```
3 1
10 1
5 1
5 2
2 5 5
```输出是：```
0 1 1
```员工年龄准确`L`或者确切地说`R`必须包括在内。 使用严格比较会错误地删除它们。 

最后一个棘手的情况是，当一方的最大年龄在根部之前停止攀登时：```
4 1
10 1
7 1
4 2
3 3
3 3 7
```所有者是员工 4。年龄 7 允许的最高祖先是员工 2，而不是员工 1。受邀集是员工 2 的子树，年龄至少为 3，给出：```
0 1 1 1
```总是从根开始的粗心实现会错误地计算员工 1。 

## 方法

 直接的方法是独立处理各方。 从所有者开始，我们可以运行一个 DFS，仅输入年龄在聚会区间内的员工。 每一位被拜访的员工都会收到一份多份邀请。 这是正确的，因为 DFS 严格遵循每个受邀员工必须通过有效员工进行连接的规则。 

当多方重叠时就会出现问题。 在最坏的情况下，每一方都可以拜访每个员工，从而提供 O(NM) 的工作量。 当这两个值都达到 100000 时，树木访问次数约为 100 亿次。 

有用的观察是，一次方可以转化为几何更新。 找到最高有效祖先后`h`、党影响着每一位员工`v`满足两个条件：`v`位于 的子树内部`h`， 和`age[v] >= L`。 

如果我们对树运行 DFS 顺序，每个子树都会成为一个连续的区间。 员工`v`由点表示`(tin[v], age[v])`。 一方变为矩形更新：`tin[h] <= tin[v] <= tout[h]`和`age[v] >= L`。 

我们需要应用许多此类更新并询问每个员工点的价值。 这可以通过按年龄对员工进行排序来离线解决。 在处理从年轻到年长的员工时，我们激活了每一个已经达到最低年龄的群体。 主动方只需在欧拉区间上加一即可，这可以通过芬威克树来处理。 

最终的变换是：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(NM) | O(N) | 太慢了|
 | 最佳 | O((N + M) log N) | O((N + M) log N) | O(N log N) | O(N log N) | 已接受 |

 ## 算法演练

 1.构建员工树并计算Euler巡回职位。 对于每一位员工，商店`tin`和`tout`，因此每个子树都成为欧拉阶中的一个区间。 
2.为祖先建造二元升降台。 年龄条件在到根的路径上是单调的，因此我们可以以2的幂向上跳跃，找到年龄不超过该方最大年龄的最高祖先。 
3. 对于每一方，从其所有者开始并使用二元提升向上爬。 如果祖先候选者的年龄最大`R`，移到那里。 最终员工是最高有效祖先`h`。 
4、将聚会转化为欧拉间隔离线更新`[tin[h], tout[h]]`和最低年龄`L`。 
5. 越来越多地按年龄对员工进行排序，并越来越多地按最低年龄对聚会更新进行排序。 在回答员工年龄之前`A`，将每一方添加为`L <= A`作为欧拉间隔上的范围增量转换为 Fenwick 树。 
6、查询员工Euler位置处的Fenwick树。 该值是覆盖该员工的活动方矩形的数量，这正是邀请他们的方的数量。 

为什么它有效：

 对于一个政党来说，最高的祖先`h`最多年龄`R`是可以与所有者保持连接的最高点。 外面的一切`h`的子树需要跨越年龄已经太大的父边缘。 里面`h`的子树，所有年龄最多自动`R`因为后代不可能比祖先更老。 唯一剩下的要求是至少年龄`L`，由离线扫描处理。 每个员工都会收到一个增量，该增量恰好对应于矩形包含其的各方`(tin, age)`点，因此最终的 Fenwick 查询会产生所需的计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    age = [0] * (n + 1)
    graph = [[] for _ in range(n + 1)]

    for i in range(1, n + 1):
        a, b = map(int, input().split())
        age[i] = a
        if i != b:
            graph[b].append(i)

    LOG = (n + 1).bit_length()
    up = [[1] * (n + 1) for _ in range(LOG)]

    stack = [1]
    order = [1]
    parent = [1] * (n + 1)

    while stack:
        u = stack.pop()
        for v in graph[u]:
            parent[v] = u
            order.append(v)
            stack.append(v)

    for i in range(1, n + 1):
        up[0][i] = parent[i]

    for k in range(1, LOG):
        prev = up[k - 1]
        cur = up[k]
        for i in range(1, n + 1):
            cur[i] = prev[prev[i]]

    tin = [0] * (n + 1)
    tout = [0] * (n + 1)
    timer = 0

    stack = [(1, 0)]
    while stack:
        u, state = stack.pop()
        if state == 0:
            timer += 1
            tin[u] = timer
            stack.append((u, 1))
            for v in reversed(graph[u]):
                stack.append((v, 0))
        else:
            tout[u] = timer

    def highest(o, r):
        u = o
        for k in range(LOG - 1, -1, -1):
            if age[up[k][u]] <= r:
                u = up[k][u]
        return u

    updates = []
    for _ in range(m):
        o, l, r = map(int, input().split())
        h = highest(o, r)
        updates.append((l, tin[h], tout[h]))

    updates.sort()
    employees = sorted((age[i], tin[i], i) for i in range(1, n + 1))

    bit = [0] * (n + 2)

    def add(idx, val):
        while idx <= n:
            bit[idx] += val
            idx += idx & -idx

    def range_add(l, r, val):
        add(l, val)
        add(r + 1, -val)

    def query(idx):
        res = 0
        while idx:
            res += bit[idx]
            idx -= idx & -idx
        return res

    ans = [0] * (n + 1)
    p = 0

    for a, pos, idx in employees:
        while p < m and updates[p][0] <= a:
            _, l, r = updates[p]
            range_add(l, r, 1)
            p += 1
        ans[idx] = query(pos)

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```代码的第一部分构造有根树和二元提升表。 根在祖先表中指向自身，这避免了在攀爬到达公司层次结构顶部时的特殊处理。 

Euler 巡演是迭代计算的，以避免 Python 递归限制。 重要的属性是一个子树中的所有员工在`tin[u]`和`tout[u]`。 

这`highest`函数使用从大跳转到小跳转的二进制提升。 由于年龄只会在树向下移动时减少，因此如果跳转目​​标仍在允许的最大年龄范围内，则当前职位和该跳转目标之间的每个员工也是有效的。 

芬威克树存储欧拉位置上的差异数组。 一方更新使用两个点更新将 1 添加到整个子树区间。 年龄扫描可确保在当前员工年龄达到允许的最低年龄时准确插入一方。 

不需要大值的乘法，因此 Python 整数溢出不是问题。 间隔更新使用`r + 1`; 这个额外的位置是无害的，因为芬威克树有大小`n + 1`，并且它可以防止子树末尾出现差一错误。

 ## 边缘情况

 仅根的情况之所以有效，是因为二进制提升表将根存储为其自己的祖先。 这`highest`函数永远不会离开有效范围，并正确地将根保留为尽可能最高的员工。 

对于边界年龄情况：```
3 1
5 1
5 1
5 2
2 5 5
```该方拥有所有者 2 和范围`[5,5]`。 业主和雇员 3 具有确切的允许年龄，因此两者都被计算在内。 在扫描过程中，在处理 5 岁员工之前插入该方，因为`L <= age`，欧拉区间包括两个雇员。 

对于停止爬升的情况：```
4 1
10 1
7 1
4 2
3 3
3 3 7
```所有者是员工 4。二进制提升尝试向上移动，但员工 1 的年龄为 10，超出了最大年龄 7。最高有效祖先仍然是员工 2。更新仅覆盖员工 2 的子树，因此员工 1 永远不会收到派对增量。 

离线扫描统一处理所有此类情况，因为每一方都由同时满足子树条件和最小年龄条件的员工代表。
