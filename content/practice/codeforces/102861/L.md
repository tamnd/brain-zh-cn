 # 问题理解

 该板是由大写字母组成的矩形网格。 集合中的单词不必按其原始顺序出现。 相反，我们感兴趣的是行、列或对角线的任何连续段，其字母可以重新排列以形成给定单词之一。 

如果一个单元属于至少一个这样的段，则该单元被称为特殊单元。 任务是计算所有有效的字谜片段覆盖了多少个不同的单元格。 

网格尺寸最多为 40 x 40，因此棋盘最多包含 1600 个单元格。 该集合最多包含 20 个单词，每个单词的长度最多为 15 个。这些限制足够小，我们可以检查许多可能的片段，但它们排除了在整个板中为每个单词重复执行昂贵搜索的解决方案。 重要的限制是最大字长。 有效段很短，因此逐个字符检查候选段的成本很低。 

一些细节很容易破坏简单的实现。 即使字母的顺序完全不同，片段也可能与单词匹配。 例如：```
2 3
BCA
XXX
1
ABC
```答案是`3`，因为第一行包含`BCA`，这是一个字谜`ABC`。 仅搜索单词的确切顺序的解决方案将错误地返回零。 

一个单元格可以属于多个匹配段，但只能计数一次。 例如：```
2 2
AA
AA
1
AA
```四个单元格中的每一个都属于多个匹配的段，但正确答案是`4`。 每次发现匹配项时都会增加答案的粗心实现会导致计数过多。 

相同的字长可以在棋盘方向中出现多次，并且一个字可以沿着对角线以及行和列进行匹配。 例如：```
3 3
ABC
XXX
XXX
1
ACB
```顶行本身还不够，因为必须重新排列字母。 正确的解决方案会检查整个段并比较字母频率。 

# 方法

 直接的方法是尝试董事会的每个可能的部分。 对于每个起始位置、四个有用方向中的每一个以及每个可能的单词长度，我们可以收集片段中的字母并将它们的频率计数与给定单词进行比较。 这是有效的，因为字谜完全取决于每个字母出现的次数。 

如果暴力方法对每个单词都重复工作，那么它的效率就会很低。 在最大的情况下，大约有 1600 个起始位置、四个方向、许多可能的长度以及最多 20 个要比较的单词。 为每个单词单独构建和比较频率数组的版本可以执行数百万次不必要的操作。 

关键的观察结果是单词的长度很小，并且没有两个输入单词是彼此的字谜。 我们只需要知道一段的频率向量是否属于目标频率向量集合。 我们可以将所有目标向量存储在哈希集中，并将所有单词的查找减少为单个操作。 

由于最大长度仅为 15，因此即使重建每个候选片段的频率计数也足够快。 所有相关长度和方向上只有几万个候选片段。 这提供了比维护复杂的滑动窗口更简单的解决方案，同时仍然保持在限制范围内。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(D * L * C * K * P) | O(N) | 如果单独比较每个单词太慢 |
 | 频率哈希 | O(D * L * C * K * P) | O(N + L * C) | O(N + L * C) | 已接受 |

 这里，`D`是四个方向，`K`是不同字长的数量，并且`P`是最大字长。 在给定的范围内，字符操作的实际数量仍然很小。 

# 算法演练

 1. 读取每个目标单词并将其转换为包含 26 个字母中每个字母的计数的频率向量。 将这些向量存储在一个集合中。 由于两个目标词绝不是字谜词，因此每个存储的向量准确地标识一个目标词。 
2. 记录目标词的不同长度。 仅当段的长度是这些值之一时，段才能匹配单词，因此检查其他长度只会产生不必要的工作。 
3. 对于每个可能的字长和四个方向中的每一个，检查可以包含完整段的每个起始单元格。 四个方向是水平、垂直、对角线右下和对角线左下。 相反的方向是不必要的，因为它们以相反的顺序描述相同的单元格。 
4. 构建每个候选片段的频率向量并检查其是否存在于存储的目标集中。 如果是，则将此段的每个单元格标记为特殊。 
5. 处理完所有片段后，对标记的单元进行计数。 每个单元格都会计数一次，因为标记存储为布尔状态而不是匹配数。 

为什么它有效：

 每个可能的有效字谜片段必须具有目标长度之一，并且必须位于四个选定方向之一。 该算法检查每个这样的段。 当一个片段的字母频率向量与目标单词之一匹配时，该片段就被准确地接受，这正是字谜词的定义。 每个接受的段都会标记其所有单元格，因此每个特殊单元格都会被标记。 由于最终答案对标记的单元格而不是匹配项进行计数，因此重叠的段不会导致过度计数。 

# Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    L, C = map(int, input().split())
    grid = [input().strip() for _ in range(L)]

    N = int(input())

    target = set()
    lengths = set()

    for _ in range(N):
        word = input().strip()
        cnt = [0] * 26
        for ch in word:
            cnt[ord(ch) - ord('A')] += 1
        target.add(tuple(cnt))
        lengths.add(len(word))

    marked = [[False] * C for _ in range(L)]

    directions = [(0, 1), (1, 0), (1, 1), (1, -1)]

    for length in lengths:
        for dr, dc in directions:
            for r in range(L):
                for c in range(C):
                    end_r = r + dr * (length - 1)
                    end_c = c + dc * (length - 1)

                    if not (0 <= end_r < L and 0 <= end_c < C):
                        continue

                    cnt = [0] * 26
                    cells = []

                    rr, cc = r, c
                    for _ in range(length):
                        cnt[ord(grid[rr][cc]) - ord('A')] += 1
                        cells.append((rr, cc))
                        rr += dr
                        cc += dc

                    if tuple(cnt) in target:
                        for x, y in cells:
                            marked[x][y] = True

    ans = 0
    for row in marked:
        ans += sum(row)

    print(ans)

if __name__ == "__main__":
    solve()
```输入被读取一次，目标词立即转换为频率向量。 使用元组允许将向量存储在 Python 集中，从而提供恒定的平均时间成员资格检查。 

这四个方向就足够了，因为字谜不依赖于阅读顺序。 从左到右的段及其反向包含相同的单元格和相同的字母，因此检查两者会重复工作。 

对于每个候选段，代码首先验证端点是否保留在板内。 这可以避免越界访问，也是对角线方向可能引入错误的主要地方。 收集片段后，仅当其频率向量与目标匹配时，代码才标记其单元格。 

这`marked`数组与匹配过程是分开的。 这是必要的，因为许多不同的字谜片段可以共享单元，并且问题要求单元的数量而不是出现的次数。

 # 边缘情况

 仅在重新排列字母后才匹配的段才会被处理，因为该算法从不直接比较字符串。 对于输入：```
2 3
BCA
XXX
1
ABC
```该段`BCA`创建频率向量`{A:1, B:1, C:1}`，它等于存储的向量`ABC`。 第一行中的三个单元格被标记，产生正确的答案`3`。 

通过仅存储单元是否曾经出现在有效段中来处理重叠匹配。 为了：```
2 2
AA
AA
1
AA
```每个可能的水平、垂直和对角线段的长度都匹配两个。 该算法标记了四个位置中的每一个，并且最终计数保持不变`4`而不是单独计算每个出现的次数。 

棋盘边界的部分是安全的，因为每个候选者在访问任何字符之前都会检查其最终位置。 为了：```
3 3
ABC
XXX
XXX
1
CBA
```从左到右检查顶行为`ABC`，其频率向量与`CBA`。 结果是`3`，并且在检查将离开棋盘的方向时不会发生无效访问。
