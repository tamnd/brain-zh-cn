 ## 解决方案
 ## 问题理解

 专辑有`N`空槽，每个数据包都会贡献随机数量的贴纸。 数据包可以包含介于`A`和`B`，每个值都有相同的概率。 目标不是模拟一个收集过程，而是计算所需的平均数据包数量，直到累积的贴纸达到至少`N`。 

输入值描述了贴纸的目标数量以及最小和最大可能的数据包大小。 输出是一个浮点值，表示所需的预期数据包数量。 

约束条件`N <= 10^6`是主要的困难。 尝试所有可能的集合历史记录的解决方案是不可能的，因为历史记录的数量呈指数级增长。 即使是对每个状态的每个可能的数据包大小执行转换的动态编程解决方案也需要大约`N * (B - A + 1)`操作，可以达到`10^12`当两个值都很大时。 该解决方案必须在接近恒定的时间内处理每个状态。 

在多种情况下，直接公式可能会失败。 第一个是数据包可以包含零个贴纸的情况。 例如，使用输入`1 0 1`，一个数据包提供零个或一个贴纸。 预期的答案是`2.0`，因为第一个数据包成功的概率是一半，并且尝试次数遵循几何分布。 除以平均数据包大小的公式将失败，因为当可能出现零进度时，平均值不足以提供足够的信息。 

另一个边缘情况是每个数据包具有相同的大小。 用于输入`30 3 3`，每包正好有三张贴纸，所以答案是`10.0`。 将范围视为包含多个同样可能的值会导致范围长度的错误除法。 

当最小数据包大小已经完成小状态时，出现最终边界情况。 用于输入`5 5 10`，一包总能完成专辑，所以答案是`1.0`。 意外包含不可能的先前状态的重复可能会产生大于 1 的值。 

## 方法

 一个简单的动态规划解决方案定义`dp[x]`作为预期所需的数据包数量`x`贴纸仍然缺失。 如果数据包包含`k`贴纸，剩余金额变为`max(0, x-k)`。 复发率是`dp[x] = 1 + average(dp[max(0, x-k)])`超过所有可能的数据包大小。 

这种方法是正确的，因为每个州只依赖于较小的剩余量。 问题是过渡。 对于每一个`x`，检查每个值`A`到`B`可能需要多达一百万次操作。 对于一百万个州来说，这大约是`10^12`最坏情况下的操作，远远超出了极限。 

关键的观察结果是转换使用了一系列连续的先前状态。 什么时候`A > 0`，值`dp[x-B]`通过`dp[x-A]`是唯一的非零贡献。 什么时候`A = 0`，过渡还包含`dp[x]`因为零贴纸包会使状态保持不变。 在这种情况下，可以用代数方式重新排列递归，以便仍然在恒定时间内计算当前值。 

维护动态编程值的前缀和可以让我们在恒定时间内检索任何连续的范围和。 原来的二次转变变成线性扫描`1`到`N`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N(B - A + 1)) | O(N(B - A + 1)) | O(N) | 太慢了|
 | 最佳 | O(N) | O(N) | 已接受 |

 ## 算法演练

 1. 创建数组`dp`在哪里`dp[x]`存储需要收集的预期数据包数量`x`更多贴纸。 还维护`pref[x]`，所有的前缀和`dp`值高达`x`。 
2. 处理状态`1`到`N`。 我们总是首先解决较小的缺失量，这意味着递归所需的每个值都是已知的。 
3.如果`A > 0`，处理正常复发。 可能的先前状态形成区间`max(0, x-B)`到`x-A`。 使用前缀和来获取该区间的总和并计算：`dp[x] = 1 + interval_sum / (B-A+1)`这`1`代表购买下一个数据包，平均值代表该数据包之后的预期剩余工作量。 
4.如果`A = 0`，将当前状态与重现隔离。 零贴纸包贡献`dp[x]`本身，因此方程变为：`dp[x] = (B+1 + sum(dp[j]) for j in [max(0,x-B), x-1]) / B`这避免了循环依赖并允许相同的前向迭代。 
5.计算完每个`dp[x]`，更新其前缀和，以便将来的状态可以立即查询范围。 

工作原理：动态编程状态准确地表示了每个可能丢失的贴纸数量的预期剩余数据包数量。 复发直接源于对购买的第一包的调节。 前缀和仅改变所需平均值的计算方式，而不改变递推的数学值。 的特殊处理`A = 0`消除了当前状态依赖于自身的唯一情况，因此每个状态都是根据已经最终确定的值计算的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, A, B = map(int, input().split())

    dp = [0.0] * (N + 1)
    pref = [0.0] * (N + 1)

    count = B - A + 1

    for x in range(1, N + 1):
        if A == 0:
            left = max(0, x - B)
            if left == 0:
                previous_sum = pref[x - 1]
            else:
                previous_sum = pref[x - 1] - pref[left - 1]
            dp[x] = (B + 1 + previous_sum) / B
        else:
            left = max(0, x - B)
            right = x - A
            if right >= left:
                interval_sum = pref[right]
                if left > 0:
                    interval_sum -= pref[left - 1]
            else:
                interval_sum = 0.0
            dp[x] = 1.0 + interval_sum / count

        pref[x] = pref[x - 1] + dp[x]

    print("{:.10f}".format(dp[N]))

if __name__ == "__main__":
    solve()
```数组`dp`存储每个较小目标的答案，同时`pref`存储累积和，以便无需循环即可检索一系列状态。 前缀和更新在计算状态后立即发生，因为后面的状态取决于所有先前的值。 

分行为`A == 0`是必要的，因为普通递归包含未知值`dp[x]`。 将该项移至左侧后，分母变为`B`， 不是`B+1`。 缺少这种代数调整是最常见的实施错误。 

为了`A > 0`,`right = x - A`是接收到最小数据包后可以保留的最大先前状态。 下界使用`max(0, x-B)`因为收到大包就可以完整完成专辑，对应的是`dp[0] = 0`。 

Python 浮点值就足够了，因为所需的误差容限是`10^-5`。

用于输入`100 1 10`，每个数据包都取得积极进展，因此使用正常转换。 

| x| 先前状态的范围 | dp[x] | dp[x] |
 | ---| ---| ---|

 该轨迹表明只需要先前值的滑动区间。 前缀和允许立即查询该间隔。

def solve_data(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    N, A, B = map(int, sys.stdin.readline().split())

    pref = [0.0] * (N + 1)

            s = pref[x - 1]
            if left > 0:
                s -= pref[left - 1]

 ## 边缘情况

 对于`1 0 1`，算法进入零最小分支。 之前的总和只有`dp[0]`，为零，所以`dp[1] = (1 + 1 + 0) / 1 = 2`。 这与第一个成功的单贴纸数据包之前的预期尝试次数相匹配。 

为了`30 3 3`，每个转换只有一种可能的数据包大小。 该区间恰好包含当前状态后面三个位置的状态，因此值变为`dp[3] = 1`,`dp[6] = 2`，最后`dp[30] = 10`。 确定性行为被保留。 

为了`5 5 10`，所有数据包大小都足以立即完成。 对于每个州，从`1`到`5`，过渡范围为空，留下`dp[x] = 1`。 最终答案是正确的一包。 

为了`1000000 1000000 1000000`，该算法不会尝试分配转换表或循环遍历数据包大小。 它执行一百万次恒定时间更新并返回`1.0`，这说明了为什么线性方法是必要的。
