 ## 解决方案
 ## 问题理解

 我们提供了两种类型的物品，红色电锯和蓝色电锯，我们希望将所有这些物品分发给一定数量的杂耍者。 每个杂耍者都会收到一对非负整数，描述他们处理的红色和蓝色电锯的数量，并且每个电锯必须恰好分配给一个杂耍者。 

关键的限制是不允许两个杂耍者拥有相同的对。 如果一位杂耍者有$(r, b)$，没有其他杂耍者可能有相同的$(r, b)$。 目标是最大限度地增加杂耍者的数量，同时消耗掉所有杂耍者$R$红色和$B$蓝色电锯。 

约束条件$R, B \le 500$跨测试用例表明每个测试用例的二次或接近二次构造是可以接受的。 任何涉及分布指数枚举的方法都是不可行的，但结构化组合结构或小状态空间上的贪婪包装是合适的。 

当一个人试图贪婪地首先分配所有红色或首先分配所有蓝色时，就会出现微妙的失败情况。 这种情况会被打破，因为最佳解决方案将两种颜色混合以创建更多不同的颜色对。 

例如，如果$R = 3, B = 3$, 分配$(1,0),(1,0),(1,3)$风格分裂会浪费多样性，而平衡的集合就像$(0,0),(1,1),(2,2)$由于未使用的约束，甚至无效，因此朴素的对称结构很容易在不检查可行性的情况下多计数或少计数。 

## 方法

 暴力解释会尝试划分$R$和$B$进入$k$不同的对$(r_i, b_i)$这样$\sum r_i = R$和$\sum b_i = B$。 这成为一个受约束的整数划分问题，对有序对具有唯一性约束。 分割方式的数量$R$进入$k$非负部分已经是$\binom{R+k-1}{k-1}$，类似地对于$B$，所以迭代所有$k$检查可行性会导致组合爆炸。 

核心简化在于，只有不同对的数量才重要，而不是它们的具体排列。 最优策略总是对应于选择$k$按一个坐标递增的顺序排列不同的对，然后验证剩余的自由度是否允许分配总数。 该结构简化为确定最大的$k$使得存在$k$第一象限中的不同格点的坐标总和恰好为$(R, B)$当多重性被适当地分配时。 

隐藏的结构是最佳配置的行为就像填充楼梯：如果我们按$r$， 他们的$b$值必须严格避免碰撞，并且最大$k$当我们按照字典顺序使用尽可能小的不同对，同时保持总和平衡时，就可以实现。

 | --- | --- | --- | --- |
 | 暴力分割$(R,B)$| 指数| 指数| 太慢了 |
 | 贪婪地构造最大不同序列 |$O(R + B)$|$O(k)$| 已接受 |

 ## 算法演练

 我们将问题重新解释为构造最大可能的不同整数对集合$(r_i, b_i)$使得总和匹配$(R, B)$。 

### 步骤

 1.围绕不断增加的杂耍者数量对建筑进行排序$k$，因为每个杂耍者都会贡献一对独特的，并且$k$是我们最大化的。 
2.对于固定的$k$，尝试在单调结构中分配不同的对。 我们强制所有对都是不同的，因此我们可以通过增加红色计数来假设排序：$$r_1 < r_2 < \dots < r_k$$这种排序避免了对称性问题，并确保结构上的唯一性，而不是通过簿记强制执行。 
3. 在此排序下，红色的最小可能总和为$k$不同的非负整数是$$0 + 1 + 2 + \dots + (k-1) = \frac{k(k-1)}{2}$$如果这超过$R$， 然后$k$不能形成杂耍者。 
4. 最低限度地修复红色后，剩余的红色预算作为额外增量自由分配。 这不会降低可行性，因为增加任何$r_i$保留清晰度。 
5. 对蓝色计数应用相同的推理。 最小蓝和也是$\frac{k(k-1)}{2}$。 
6. 因此$k$可行当且仅当$$\frac{k(k-1)}{2} \le R \quad \text{and} \quad \frac{k(k-1)}{2} \le B$$7. 计算最大的此类$k$直接递增，直到条件失败。 

### 为什么它有效

 独特性至少迫使一个坐标中存在严格递增的序列。 任何严格递增长度序列的最小总和$k$非负整数是通过从以下位置开始的连续整数实现的$0$。 任何偏差只会增加总和，因此可行性完全由三角数界来表征。 相同的参数独立地适用于两种颜色，因为每个坐标仅受其自身总数的约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []
    for tc in range(1, T + 1):
        R, B = map(int, input().split())

        k = 0
        while True:
            need = k * (k - 1) // 2
            if need > R or need > B:
                break
            k += 1

        out.append(f"Case #{tc}: {k - 1}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现直接应用三角数可行性条件。 循环是安全的，因为$k$只增长到大约$\sqrt{R}$或者$\sqrt{B}$，在约束条件下很小。 最后减一可以纠正最后一个失败的增量。 

一个常见的陷阱是对红色和蓝色计数使用独立的贪婪分配； 正确的约束耦合可行性只能通过共享$k$，而不是通过每个魔术师的优化。

 ## 边缘情况

 像这样的案例$R = 0, B = 0$测试算法是否正确返回一个简单的杂耍者，因为$k=1$需要零总电锯并且是可行的。 

严重不平衡的情况，例如$R = 10, B = 0$表明蓝色不会将红色限制在共享三角形边界之外； 限制因素变成较小的坐标。 

边界情况，其中$R = B = \frac{k(k-1)}{2}$测试确切的饱和点，在该饱和点上，如果再多一个魔术师，就会通过将所需的最小金额增加到超出可用资源来违反可行性。
