 ## 解决方案
 ## 问题理解

 我们得到了一系列独立的测试用例。 每个测试用例提供两个整数，$n$和$m$，我们从概念上形成数字$n \cdot 245^m$。 任务不是计算这个完整值，而只是确定其以 10 为基数的最后一位数字。 

因此，真正的输出问题是关于乘积的个位数，其中一个因子是固定基数$n$，另一个因素是 245 的大幂。由于仅要求最后一位数字，因此所有较高位的值都是无关紧要的，可以完全忽略。 

限制很大：两者$n$和$m$可以达到$10^9$，并且最多有$10^3$测试用例。 任何尝试计算的方法$245^m$直接求幂，即使是快速取幂，也是不必要的，因为指数本身很大，但我们关心的数量在结构上非常小，只有一位数。 

约束的关键含义是解决方案必须将所有内容都简化为仅对最后一位数字进行模运算。 任何处理完整整数甚至完整幂的尝试都是浪费且不必要的。 

出现微妙的边缘情况时$n = 0$。 在这种情况下，无论什么，乘积始终为零$m$，所以答案始终为 0。另一个重要的边缘情况是$m = 0$。 然后$245^0 = 1$，所以答案就是最后一位数字$n$。 如果只关注指数，这些情况很容易被忽视。 

## 方法

 一个蛮力的想法是计算$245^m$明确并乘以$n$，然后提取最后一位数字。 即使我们切换到通过平方求幂，我们仍然不必要地处理大整数。 在 Python 中，这可能会在小的输入中幸存下来，但是对于$m$最多$10^9$，除非积极减少，否则中间值会快速增长，并且由于只需要最后一位数字，因此乘法步骤变得毫无意义的开销。 

关键的观察结果是最后一位数字在乘法下循环表现。 由于我们只关心最终产品的最后一位数字，因此我们可以减少两者$n$和$245$立即模 10。 这将问题转化为计算：$$(n \bmod 10) \cdot (5^m \bmod 10)$$因为245以5结尾。 

现在结构变得非常简单。 任何 5 的幂都有一个稳定的最后一位数字：一旦我们将 5 乘以它本身，即使一次，结果总是以 5 结尾。所以对于所有$m \ge 1$,$5^m$以 5 结尾，而$5^0 = 1$。 

这将整个问题减少到每个测试用例决策的恒定时间。

 | ---| ---| ---| ---|
 | 蛮力 |$O(m)$每次测试或更差 |$O(1)$| 太慢了 |
 | 最佳 |$O(1)$每次测试 |$O(1)$| 已接受 |

 ## 算法演练

 我们将问题简化为最后一位算术并明确处理 5 的指数行为。 

1. 阅读$n$和$m$对于每个测试用例。 只有最后一位数字很重要，所以我们立即计算$n \% 10$。 
2.特殊情况处理$n = 0$。 如果第一个因子为零，则乘积始终为零，因此我们可以输出 0 而无需进一步计算。 
3. 检查是否$m = 0$。 如果是这样，则表达式变为$n \cdot 1$，所以答案很简单$n \% 10$。 
4.如果$m \ge 1$， 代替$245^m$及其最后一位数字的行为。 由于 245 以 5 结尾并且$5^m$所有正数均以 5 结尾$m$，第二个因子贡献固定的最后一位数字 5。 
5. 乘以最后一位数字$n$与 5 并输出该乘积的最后一位数字。 

关键思想是，一旦我们减少到最后一位数字，求幂就会变成一个恒定的模式。 

### 为什么它有效

 正确性来自于这样一个事实：乘积的最后一位数字仅取决于其因子的最后一位数字。 正式来说，如果$a \equiv a' \pmod{10}$和$b \equiv b' \pmod{10}$， 然后$ab \equiv a'b' \pmod{10}$。 这使我们能够替换$n$和$n \% 10$和$245^m$和$(5^m \% 10)$不影响最终答案。 

第二个性质是 5 的幂以 10 为模稳定：对于所有$m \ge 1$,$5^m \equiv 5 \pmod{10}$。 这消除了对任何求幂逻辑的需要。 因此，该算法保证产生与原始表达式相同的最后一位数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())

        if n == 0:
            print(0)
            continue

        last_n = n % 10

        if m == 0:
            print(last_n)
        else:
            print((last_n * 5) % 10)

if __name__ == "__main__":
    solve()
```该实现直接遵循最后一位算术的简化。 唯一的分支逻辑是将$m = 0$案例来自$m \ge 1$，因为幂恒等式在那里不同。 直接执行乘以 5 是安全的，因为我们只关心最后一位数字。 

最常见的错误是尝试计算$245^m$使用求幂而不提前减少模 10。 这是不必要的工作，并且掩盖了最后一位数字的简单周期性行为。

 ## 边缘情况

 对于$n = 0, m = 0$，由于零检查，算法立即返回 0，匹配$0 \cdot 1 = 0$。 

为了$n = 987, m = 0$，我们绕过电源逻辑并返回$987 \% 10 = 7$，正确处理恒等指数。 

为了$n = 20, m = 5$，我们取最后一位数字 0 并乘以 5，得到 0。即使指数很大，但减少使结果立即且稳定。 

对于非常大的$m$， 例如$10^9$，该算法不会尝试求幂。 它依赖于这样一个事实：5 的任何正幂的最后一位数字都是 5，因此无论大小如何，计算时间都保持恒定。
