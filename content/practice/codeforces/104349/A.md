 ## 解决方案
 ## 问题理解

 我们给出了以字节为单位的原始文件大小，并且必须仅使用三种可能的单位以紧凑的“人类可读”格式显示它：字节 (B)、千比字节 (KiB) 和兆比字节 (MiB)。 输出始终是一个数字，后紧跟这些单位字符串之一，没有空格。 

每个单位对应于二次方缩放。 1 KiB 等于 1024 字节，1 MiB 等于 1024 KiB，即 1024 字节的平方。 我们打印的数字必须始终是 1 到 1023 之间的整数，并且在单位之间转换时需要向下舍入。 

因此，任务是选择最大可能的单位，使得转换后的值仍然至少为 1，最大为 1023，然后输出该单位的取整整数。 

m 的约束达到 10^9，这个值足够小，我们最多只能处理 MiB 规模，因为 1024^2 约为 10^6，而 1024^3 已经超过 10^9。 这意味着决策空间非常浅：只有 B、KiB 和 MiB 重要。 

当试图总是向上转换或总是贪婪地标准化而不检查边界时，就会出现天真的错误。 例如，将 1401 字节视为 1401 B 是无效的，因为 1401 超过了 1023，但将其转换为 KiB 在向下取整后给出 1 KiB，这是有效的。 另一个陷阱是失去了数字必须保持在 [1, 1023] 范围内的规则，该规则禁止像 0 MiB 或 0 KiB 这样的输出，即使数学上是正确的。 

另一个微妙的问题是排序：如果我们先尝试 KiB，然后再尝试 MiB，即使 MiB 有效，我们也可能会错误地选择较小的单位。 例如，14510629 字节应该是 13 MiB，但粗心的方法可能会停在 KiB，因为它在四舍五入后“更早适合”。 

## 方法

 蛮力的想法是独立尝试所有三个单元。 对于每个单元，我们使用整数除法计算转换后的值，并检查它是否位于有效范围 [1, 1023] 内。 如果多个单位有效，我们选择其中最大的单位（MiB over KiB over B）。 这是有效的，因为只有三个候选者，并且每次转换都是常数时间。 

只有当我们想象一个具有许多单元或重复重新计算的广义版本时，才会出现效率低下的情况，但即使如此，结构也足够简单，暴力在实践中已经是最佳的。 

关键的观察是，单位系统是严格分层的，每一步都是 1024 的因子。这意味着我们永远不需要动态搜索或优化； 我们只需要测试固定常数的整除性并应用地板除法。 对数值范围的约束强制采用一种有效的表示形式，因此答案由使商保持在范围内的最高单位确定。

 ## 算法演练

 我们独立评估每个测试用例。 

1. 从给定大小（以字节为单位）m 开始。 这是基本表示形式，所有其他单位都是通过重复除以 1024 得出的。 
2. 检查是否可以用MiB 表示该值。 计算 m // (1024 * 1024)。 如果结果至少为 1，最多为 1023，我们立即选择 MiB 作为单位。 这是因为 MiB 是允许的最大单位，并且我们需要最压缩的表示形式。 
3. 如果 MiB 无效，请检查 KiB。 计算 m // 1024。如果该值位于 [1, 1023] 中，我们将输出包含该数字的 KiB。 
4. 如果 MiB 和 KiB 都不起作用，我们就退回到字节并直接输出 m B。 此时 m 必须已经在 [1, 1023] 中，因为否则 KiB 将是有效的。 
5. 打印与单位字符串连接的所选数字。

它的工作原理遵循以 1024 为基数的缩放结构。 每个单位恰好是前一个单位的 1024 倍，因此转换后的值由整数除法唯一确定。 输出数必须保持在 [1, 1023] 范围内的约束确保了最多有一个单元级别可以满足归一化后的条件。 由于 MiB 支配 KiB，KiB 支配 B，因此选择最高有效单元不能跳过有效的较小表示或错过有效的较大表示。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        m = int(input())

        mib = m // (1024 * 1024)
        if 1 <= mib <= 1023:
            print(str(mib) + "MiB")
            continue

        kib = m // 1024
        if 1 <= kib <= 1023:
            print(str(kib) + "KiB")
            continue

        print(str(m) + "B")

if __name__ == "__main__":
    solve()
```该解决方案直接遵循单元层次结构。 首先进行 MiB 检查，因为如果有效，它会产生最紧凑的表示。 仅当 MiB 失败时才会达到 KiB 检查，并且仅当两个缩放表示都超出允许的数字范围或太小时才使用字节。 整数除法自然会强制执行所需的舍入行为，因此不需要额外的舍入逻辑。 

一个常见的实施错误是在 MiB 之前检查 KiB，这可能会产生次优的单位。 另一个原因是忘记了 1 的下限，这可能会导致 1024 以下的小值输出为 0 KiB，这是无效的。 

## 工作示例

 首先，考虑输入 m = 1401。 

| 步骤| 米 | 米布| 基布 | 选择|
 | --- | --- | --- | --- | --- |
 | 检查 MiB | 1401 | 1401 0 | - | 没有|
 | 检查 KiB | 1401 | 1401 - | 1 | 基布 |

 这里1401 // 1024 = 1，这是有效的。 MiB 转换给出 0，这是无效的，因为它低于所需的最小数量。 该算法正确选择 KiB。 

现在考虑 m = 14510629。 

| 步骤| 米 | 米布| 基布 | 选择|
 | --- | --- | --- | --- | --- |
 | 检查 MiB | 14510629 | 13 | - | 米布|
 | 停止| - | 13 | - | 米布|

 这里 14510629 // 1048576 等于 13。这位于 [1, 1023] 范围内，因此立即选择 MiB。 KiB 永远不会被评估，因为 MiB 已经满足要求。 

这些示例展示了层次结构如何强制执行唯一选择以及地板如何与单位转换交互。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        m = int(input())

        mib = m // (1024 * 1024)
        if 1 <= mib <= 1023:
            out.append(str(mib) + "MiB")
            continue

        kib = m // 1024
        if 1 <= kib <= 1023:
            out.append(str(kib) + "KiB")
            continue

        out.append(str(m) + "B")

    return "\n".join(out)

 ## 边缘情况

 对于 m = 1，MiB 检查给出 0，KiB 检查也给出 0，因此算法回退到字节并输出 1B。 这是正确的，因为只有字节才能表示 1024 以下的值。 

对于 m = 1024，MiB 为 0，KiB 为 1，因此算法选择 1KiB。 这符合当当前单位超出有效数值范围时我们必须立即切换到下一个单位的要求。 

当m = 1048576时，MiB变为1，有效，因此算法直接选择1MiB。 这表明最高的有效单位始终是首选，并且 1024 的精确幂可以清晰地映射到更高的单位，不会产生歧义。
