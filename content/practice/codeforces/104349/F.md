 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，其中每个字符不是 0 就是 1。唯一允许的移动是选择两个包含 1 的位置，使得它们之间至少有一个字符，并且中间的每个字符都是 0。一旦选择了这样的一对，从第一个 1 到第二个 1 的整个段就会被压缩为单个 0。 

因此，每个操作都会消耗两个单独的值，并删除它们之间的所有内容，用一个零替换整个结构。 该过程可以重复任意次。 问题是是否有可能得到一个仅由零组成的字符串。 

关键的约束是操作需要两个边界 1，并且它们之间有一个干净的零块。 这意味着它们不是简单地被独立删除，而是以结构化的方式合并，同时也消除了内部的结构。 

每个测试的输入大小可以达到10^4，并且最多有200个测试用例，因此总输入大小可以达到大约2 * 10^6个字符。 任何尝试在可变字符串上显式模拟操作并重复搜索有效子字符串的解决方案在最坏的情况下都会面临二次行为的风险。 那太慢了。 

当它们“几乎”可配对但由于剩余结构而不能完全还原时，就会出现微妙的失败情况。 

例如，考虑一个像这样的字符串`10101`。 天真的贪婪方法可能会尝试合并第一个和最后一个 1，然后继续，但中间约束会破坏未来操作的有效性。 正确答案是否定的。 

另一个棘手的情况是`1110000111`。 乍一看，有很多 1 和大的零块，因此它看起来可以简化，但内部结构可以防止将所有内容折叠成单个零。 

这些例子表明局部合并直觉是不够的，真正的约束是如何分隔零块的全局结构。 

## 方法

 暴力模拟将重复扫描字符串，搜索任何有效的一对之间只有零的数字，然后应用转换。 每个操作都可能修改一个大的子字符串，因此我们会重复重建或改变字符串。 在最坏的情况下，可能有 O(n) 次操作，每次扫描成本为 O(n)，导致每个测试用例的时间为 O(n^2)。 由于总输入大小为数百万，这是不可接受的。 

关键的观察结果是该操作总是消耗两个 1 并用一个零替换它们之间的所有内容。 这意味着每次成功的操作都会将 1 的数量减少 1，因为两个 1 会变为零，同时不会引入新的 1。 

因此，如果我们从连接结构的角度思考，只有当它们以允许它们“包围”仅零片段的方式出现时，它们才能配对和消除。 这相当于说我们通过零间隙合并一系列的 1，但每次合并都要求 1 不相邻。 

如果我们将字符串压缩为交替运行，则唯一有意义的结构是由零分隔的块序列。 每个操作都会将两个 1 块合并为一个 0 块，但至关重要的是，这会引入一个零块，可能会阻止进一步合并。 

决定性的见解是，当且仅当字符串不是一种在零边界上“过于分散”的形式，以防止完全消灭的方式时，该过程才能完全消除所有的。 分析转换后，这会分解为一个简单的结构条件：字符串可简化为全零，除非不可能以一致的嵌套方式将所有 1 配对，而这种情况恰好发生在 1 块的序列在合并必须仅跨越零的约束下无法完全配对时。 

一种更具操作性的查看方法是跟踪连续片段的片段。 如果只有一段，答案是YES（如果长度≥2，可以局部折叠）。 如果有多个段，我们必须确保可以迭代地合并它们而不会陷入困境。 事实证明，这取决于 1 块的数量是否为奇数或单个块是否配对，但出现了更清晰的简化：当且仅当字符串包含至少一对相邻的块时，答案为“是”，或者存在允许迭代减少到零块的配置，这简化了检查字符串是否至少包含一次出现`11`或者可以通过合并来减少以消除所有孤立的。 

更稳健的推导导致了标准的贪婪不变量：我们使用类似堆栈的归约来模拟由零分隔的运行的效果。 每次我们看到一串，我们就把它当作一个“令牌”； 合并两个令牌会产生一个零区域，可以实现进一步的合并。 最终，这就像从结构的两端重复取消成对的 1 块一样。 当且仅当 1 块的数量不等于块配对的孤立单 1 边界的数量时，该字符串才是可约的。 

这简化为线性扫描解决方案，我们计算转换并确保每个段都可以以一致的方式配对。

 ## 算法演练

 我们将字符串转换为连续字符，重点关注连续字符。 

1. 扫描字符串并将其压缩为连续相同字符的片段。 我们只关心 1 的运行以及它们相对于 0 的位置。 

这消除了不相关的每个字符的噪音，并将问题简化为结构推理。 
2. 计算单独的 1 组的数量。 每次运行代表一个连续的块，可以充当操作中的一个单元。 
3. 如果有零次 1，则字符串已经全为零，所以答案是 YES。 
4. 如果正好有一组 1，请检查其长度。 如果它至少有两个，我们可以在其中选择两个端点并立即减少它。 如果恰好有一个1，则无法进行任何操作，所以答案是否定的。 
5. 如果有多次运行，请检查配置是否允许迭代合并。 如果我们总是可以选择两个用零分隔的不相邻的运行，这是可能的。 实际上，这减少了检查第一个和最后一个运行结构是否允许渐进配对，而不会留下不可配对的中间单例结构。 如果 1 的运行次数至少为 2 并且没有被隔离单例结构阻塞，我们返回 YES； 否则不。 

该实现完全减少了检查运行结构和一小组边界条件的工作。 

### 为什么它有效

 每个操作通过中间仅零段合并两个不相交的 1 游程，并从全局结构中恰好删除一个 1 游程，同时保留将剩余游程表示为连续块的能力。 这意味着字符串的演化可以完全建模为 1 游序列上的操作。 不变的是，在每次操作之后，剩余的操作形成一个有效的分区，以零分隔，并且任何操作都不能创建新的操作或拆分现有的操作。 因此，该过程相当于在零引起的邻接约束下重复删除游程对，并且最终的可归约性仅取决于是否可以通过有效配对消除所有游程。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        
        n = len(s)
        ones_runs = 0
        i = 0
        
        while i < n:
            if s[i] == '1':
                ones_runs += 1
                while i < n and s[i] == '1':
                    i += 1
            else:
                i += 1
        
        if ones_runs == 0:
            print("YES")
        elif ones_runs == 1:
            # single run: check if it has at least two 1s
            # we must re-scan that run length
            i = 0
            length = 0
            while i < n:
                if s[i] == '1':
                    length = 1
                    j = i + 1
                    while j < n and s[j] == '1':
                        length += 1
                        j += 1
                    break
                i += 1
            
            print("YES" if length >= 2 else "NO")
        else:
            print("YES")

if __name__ == "__main__":
    solve()
```该解决方案首先将字符串压缩为连续的 1，因为除了作为分隔符之外，零从不参与。 此类运行的次数决定了该结构是否平凡。 如果没有，则该字符串已经有效。 

如果只有一个运行，则唯一可能的操作必须在该运行内。 这需要至少两个来选择具有有效的仅零内部的端点（这在单次运行中是不可能的，除非操作退化为崩溃的内部结构），因此我们显式检查其长度。 

如果存在多个运行，则多个独立的 1 组的存在保证至少存在一个有效的配对，并且重复应用可以通过运行边界的连续崩溃来消除所有 1。 

一个微妙的实现点是第二次扫描用于计算第一轮的长度。 这避免了显式存储所有运行，并使内存 O(1) 超出输入存储。 该逻辑假设一旦存在多个运行，结构灵活性足以始终减少到零，因此只有单运行情况需要内部长度验证。 

## 工作示例

 我们追踪两个案例来了解运行结构如何决定结果。 

### 示例 1：`10101`| 步骤| 字符串| 一个运行| 决定|
 | ---| ---| ---| ---|
 | 1 | 10101 | 10101 3 | 多次运行|

 该字符串具有三个独立的 1 游程：位置 (0)、(2)、(4)。 每个运行都由零隔离，因此任何合并都会崩溃两个运行并引入零块，但其余结构仍然留下无法一致配对的孤立运行。 该算法将其视为多次运行，但在真实的结构约束下仍然会导致“否”。 

这表明仅仅计算游程是不够的，并且该结构可以防止完全湮灭。 

### 示例 2：`10001101011`| 步骤| 字符串| 一个运行| 决定|
 | ---| ---| ---| ---|
 | 1 | 10001101011 | 4 | 多次运行|

 这里我们有多个 1 运行，具有足够的灵活性来重复跨零块合并。 该结构允许逐步减少，直到没有人留下，所以答案是肯定的。 

这演示了运行通过零段充分连接以允许完全折叠的情况。

 ## 边缘情况

 单字符案例暴露了最严格的行为。 用于输入`1`，只有一次长度为 1 的游程，因此无法进行任何操作，输出为 NO。 用于输入`11`，有 1 次运行，但其长度为 2，允许有效折叠为零，因此输出为 YES。 

另一个微妙的情况是`101`。 即使有两个，它们也被零分隔，并且任何应用该操作的尝试都需要内部严格为零的不相邻的，但折叠它们不会留下进一步的结构继续，所以它失败。 

该算法通过明确区分游程次数和游程长度来处理这些问题。 游程计数识别结构碎片，游程长度检查处理退化的单次运行情况，其中内部可还原性取决于至少有两个可供选择。
