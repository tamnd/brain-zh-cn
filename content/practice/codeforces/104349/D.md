 ## 解决方案
 ## 问题理解

 我们得到了同一组数字从 1 到 n 的两种排列。 每个玩家拥有一个数组，并且在一次移动中允许玩家从自己的数组中删除任何单个元素。 每次删除后，两个数组都会有效收缩，并且保留剩余元素的相对顺序。 

当两个数组变得与序列相同时，游戏结束，这意味着它们具有相同的长度并且在每个位置都匹配。 两个玩家都采取最佳行动，任务是确定两个阵列达到相同状态所需的最小删除移动总数。 

解释该过程的一个有用方法是，我们试图找到两个数组都可以简化为的公共子序列，因为删除仅删除元素，同时保留顺序。 因此，最终的相同数组必须是在两种排列中都作为子序列出现的序列。 当双方都删除了除公共子序列之外的所有内容时，游戏结束。 

因此，答案是由我们可以在两个数组中保持不变同时保持位置一致性的最长序列驱动的。 

约束条件很严格：n 最多可达 100000，并且跨测试用例求和最多可达 100000。这会立即排除每个测试用例的任何二次方法甚至 n 对数平方方法。 任何解必须本质上是线性的或线性算数的。 

一个天真的但诱人的想法是模拟删除或尝试所有可能的最终子序列。 这是失败的，因为子序列的数量是指数级的。 另一种常见的错误尝试是在不考虑全局一致性的情况下贪婪地匹配位置，当两个排列之间的相对排序约束发生冲突时，这种尝试就会中断。 

例如，如果 A = [1, 2, 3, 4] 且 B = [2, 1, 4, 3]，人们可能会贪婪地尝试匹配相等位置或早期匹配，但任何本地决策都会忽略只有全局一致的子序列才能在两个数组中的删除中幸存下来。 

## 方法

 关键的视角转变是停止思考删除，而是思考我们可以同时保留什么。 

由于两个数组都是排列，因此每个值在每个数组中只出现一次。 这允许我们将一种排列编码为另一种排列上的位置图。 具体来说，如果我们固定数组 A，我们可以将每个值 x 映射到它在 A 中的索引。然后数组 B 根据其值在 A 中出现的位置成为索引序列。 

这将问题转换为经典结构：我们现在想要转换后的数组的最长递增子序列。 任何递增子序列都对应于在两种排列中以相同相对顺序出现的值，这正是能够在删除中幸存下来的公共子序列所需要的。 

一旦我们计算出 LIS 长度，即 L，它表示两个数组中可以以相同顺序保留的元素的最大数量。 由于两个数组最终必须完全等于保留的序列，因此每个数组必须删除 n − L 个元素。 因此，两个玩家的删除总数为 2(n − L)。 

暴力方法会尝试 A 的所有子序列，并检查它是否以相同的顺序出现在 B 中，该顺序是指数的。 LIS 简化将整个兼容性条件压缩为单个序列优化问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（尝试所有子序列）| O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 最佳（通过位置映射的 LIS）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们逐个测试用例进行测试。

1. 构建一个位置数组 pos，使得 pos[x] 是排列 A 中值 x 的索引。这让我们可以将值转换为它们在 A 中的相对顺序。 
2. 将排列 B 变换为数组 T，其中 T[i] = pos[B[i]]。 现在T代表在A的坐标系中表达的B。 
3. 使用尾部数组的标准耐心排序技术计算 T 的最长递增子序列的长度。 每个元素都是使用二分搜索插入的。 
4. 设 L 为 LIS 长度。 最终答案是 2 * (n − L)。 

步骤 3 有效的原因是 T 中的任何递增子序列都对应于 A 中递增的索引，这意味着相应的值在 A 和 B 中以相同的顺序出现。 

### 为什么它有效

 转换后的序列上的 LIS 准确捕获了在任一排列中都可以保留且不违反顺序的最大元素集。 因为两个数组中的每个数字都是唯一的，所以保留 A 中的顺序相当于需要增加 A 中的索引，而 B 中的匹配顺序是通过构造 T 来保证的。每次删除都会对称地减少数组，直到仅保留此最大一致结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from bisect import bisect_left

def lis_length(arr):
    tails = []
    for x in arr:
        i = bisect_left(tails, x)
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        A = list(map(int, input().split()))
        B = list(map(int, input().split()))
        
        pos = [0] * (n + 1)
        for i, v in enumerate(A):
            pos[v] = i
        
        T = [pos[v] for v in B]
        L = lis_length(T)
        out.append(str(2 * (n - L)))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案首先构建 A 的位置图，这对于将第二个排列转换为可比较的数字序列至关重要。 转换为 T 是关键的归约步骤，必须小心完成，因为这里的任何错误都会破坏排序逻辑。 

LIS 函数使用带有二分搜索的贪婪尾部数组。 不变的是 tails[i] 存储长度为 i+1 的递增子序列的最小可能结束值。 这确保了最佳的扩展可能性。 

最后，答案计算直接反映了两个数组必须删除所有不在所选公共子序列中的元素。 

## 工作示例

 ### 示例 1

 输入：

 A = [1, 2, 3, 4], B = [2, 1, 4, 3]

 A位置图：

 1→0、2→1、3→2、4→3

 改造后的B：

 T = [1, 0, 3, 2]

 LIS计算：

 | 步骤| x| 尾巴|
 | ---| ---| ---|
 | 1 | 1 | [1] |
 | 2 | 0 | [0]|
 | 3 | 3 | [0, 3] |
 | 4 | 2 | [0, 2] |

 L = 2

 答案 = 2 * (4 − 2) = 4

 这表明在两种排列中只能以一致的顺序保留两个元素。 

### 示例 2

 输入：

 A = [4, 2, 3, 1], B = [4, 3, 2, 1]

 A位置图：

 4→0、2→1、3→2、1→3

 改造后的B：

 T = [0, 2, 1, 3]

 LIS：

 | 步骤| x| 尾巴|
 | ---| ---| ---|
 | 1 | 0 | [0]|
 | 2 | 2 | [0, 2] |
 | 3 | 1 | [0, 1] |
 | 4 | 3 | [0, 1, 3] |

 L = 3

 答案 = 2 * (4 − 3) = 2

 这表明，即使两种排列严重混合，如果相对结构部分对齐，仍然可以存在长一致子序列。

 ## 边缘情况

 一对完全相同的排列产生严格递增的变换序列，因此 LIS 等于 n 并且答案为零。 该算法自然地处理这个问题，因为每个元素都扩展了 tails 数组而不进行替换。 

完全反转的排列会产生严格递减的变换序列，因此 LIS 始终为 1。代码正确地重复替换尾部条目，并以长度 1 结尾，产生 2(n − 1)。 

小 n 的情况（例如 n = 1 或 n = 2）无需特殊逻辑即可处理，因为 LIS 计算和位置映射都会安全降级：当 n = 1 时，T 有一个元素，LIS 为 1，如预期那样给出零删除。
