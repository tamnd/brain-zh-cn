 ## 解决方案
 ## 问题理解

 我们得到一个字符串`s`长度`n`。 从这个字符串中，我们可以执行旋转操作：选择分割位置`k`, 去掉前缀`s[0:k]`，并将其附加到末尾。 这会产生字符串的循环移位。 自从`k`范围可以从 1 到`n`，正好有`n`可能的轮换。 

任务是考虑所有这些旋转并返回字典顺序最小的旋转。 

字典比较是通常的字典顺序：我们从左到右比较两个字符串，第一个不同的字符决定顺序。 

约束条件`n ≤ 3 × 10^5`立即排除显式生成所有旋转并对它们进行排序。 构造每个旋转需要`O(n)`，并为所有人做这件事`n`轮班给出`O(n^2)`，这对于 1 秒来说太慢了。 

当所有字符都相同时，会出现微妙的边缘情况，例如`"aaaaa"`。 每次旋转都是相同的，因此答案是相同的字符串。 任何正确的解决方案都必须自然地处理这个问题，而无需额外的逻辑。 

另一种边缘情况是最小字符多次出现。 例如，`"baca"`。 “从最小的字符开始”的天真的贪婪想法是不够的，因为多个候选者仍然必须作为完整的循环字符串进行比较：```
baca → baca, acab, caba, abac
```答案是`"abac"`，它来自后来发生的`'a'`，不是第一个。 

因此，问题是在字典顺序下选择最佳循环移位。 

## 方法

 直接方法很简单：生成每个轮换，比较它们，并保留最好的。 每次旋转都需要切割绳子，成本`O(n)`，并且有`n`旋转，给予`O(n^2)`总工作量。 和`n`最多 300,000 个，这意味着在最坏的情况下大约需要 900 亿个字符操作，这是不可行的。 

关键的观察是所有候选字符串都是双倍字符串的子串`s + s`。 每次旋转对应一个长度的子串`n`从索引开始`i`在这个双重字符串中，对于`0 ≤ i < n`。 任务变成选择字典顺序最小的固定长度子串`n`在这些起始位置中。 

一个简单的改进可能是在扫描候选者时逐个字符地比较候选子字符串，但如果许多前缀匹配，最坏情况的行为仍然是二次的。 

关键的结构见解是我们不是选择任意子串，而是选择最小循环旋转。 这是一个经典问题，可以使用两指针消除策略（通常称为布斯算法）在线性时间内解决。 它保留候选起始位置，并通过相互比较它们的字典顺序来消除那些不能达到最优的位置。 

我们不是显式地比较所有对，而是在每个字符的摊销常数时间内逐步丢弃主导的起始位置，从而实现线性复杂性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 布斯算法 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们应用布斯算法来查找字典顺序最小循环旋转的起始索引。 

1. 我们在概念上使用字符串`t = s + s`。 这允许长度的每个循环移位`n`显示为连续子串`t`。 
2. 我们维护一个候选起始索引`i`以及比较指标`j`， 最初`i = 0`和`j = 1`。 我们还跟踪当前的偏移量`k`这代表我们在两个候选者之间匹配字符的程度。 
3.我们比较人物`t[i + k]`和`t[j + k]`。 如果它们相等，我们就递增`k`因为两个旋转都符合该位置。 
4. 如果发生不匹配，我们确定哪个旋转在该偏移量处按字典顺序更小。 如果`t[i + k] < t[j + k]`，然后开始旋转`j`无法击败`i`，所以我们丢弃所有从`j`到`j + k`并设置`j = j + k + 1`。 如果相反的情况成立，我们丢弃范围`i`到`i + k`并设置`i = i + k + 1`，并交换`i`和`j`保留`i`作为当前的最佳人选。 
5. 如果`i == j`，我们增加`j`确保有两个不同的候选人。 
6. 我们继续直到`j`达到`n`。 答案是子串`t[i:i+n]`。 

关键思想是一旦两次旋转的位置不同`k`，失败片段中的所有旋转也更差，因此我们可以安全地完全跳过它们，而不是一一检查它们。 

### 为什么它有效

 该算法维护一组候选起始位置，使得任何被丢弃的位置都无法成为最佳位置。 两个起始点之间的每次比较都会根据第一个不匹配消除整个无效候选块。 由于字典顺序是由第一个不同的字符确定的，因此在位置处丢失的任何旋转`k`对抗另一个人以后不会变得更好。 这保证了剩余的候选人`i`是所有循环移位中最小的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def booth(s: str) -> int:
    t = s + s
    n = len(s)
    
    i, j, k = 0, 1, 0
    
    while j < n and i < n and k < n:
        if t[i + k] == t[j + k]:
            k += 1
            continue
        
        if t[i + k] > t[j + k]:
            i = i + k + 1
            if i <= j:
                i = j + 1
        else:
            j = j + k + 1
            if j <= i:
                j = i + 1
        
        k = 0
    
    start = min(i, j)
    return start

def solve():
    n = int(input().strip())
    s = input().strip()
    
    idx = booth(s)
    n = len(s)
    t = s + s
    print(t[idx:idx + n])

if __name__ == "__main__":
    solve()
```该实现构建一次双倍字符串，以便循环旋转变成线性子字符串。 两个指针`i`和`j`代表竞争轮换开始。 变量`k`跟踪在需要做出决定之前我们对两次轮换的匹配程度。 

一个常见的实施陷阱是忘记重置`k`不匹配之后。 如果没有此重置，比较会错误地假定不相关段之间的对齐。 另一个微妙之处是确保索引保持在原始字符串长度的范围内`n`，不是双倍的字符串长度`2n`，因为只有`n`起始职位是有效的候选人。 

最终的子字符串提取使用所选的起始索引并精确切片`n`字符，保证完整旋转。

 ## 边缘情况

 对于像这样的单字符字符串`"a"`，算法初始化`i = 0`和`j = 1`， 但`j`立即超出界限，所以索引`0`被选中。 输出是`"a"`。 

对于具有相同字符的字符串，例如`"bbbbbb"`,每次比较`t[i+k] == t[j+k]`继续直到`k = n`，并且不会发生消除。 算法返回`0`，生成原始字符串不变。 

对于最佳旋转发生较晚的字符串，例如`"bcaac"`，一旦在某个偏移处遇到严格较小的字符，该算法就会丢弃早期候选字符，从而确保在没有显式枚举的情况下保留较晚的最佳开始。
