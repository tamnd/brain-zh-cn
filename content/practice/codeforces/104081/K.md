 ## 解决方案
 ## 问题理解

 我们得到一个长度的数组$n$，并且每个元素都是非负整数。 从这个数组中，我们考虑每个连续的子数组，每个子数组的权重等于其元素之和。 

如果我们列出所有子数组总和并按非递减顺序对它们进行排序，则系统会要求我们回答多个查询。 每个查询给出一个整数$k$，我们必须输出$k$- 该排序列表中第一个最小的子数组总和。 

重要的隐藏结构是，虽然有$O(n^2)$子数组中，数组仅包含零和正值，因此当我们扩展或缩小窗口时，子数组和的行为是单调的。 这种单调性使得每次检查都能在近线性时间内解决问题。 

如果$n$很大，说最多$2 \times 10^5$，枚举所有子数组已经产生了大约$2 \times 10^{10}$总和，这是不可能明确排序的。 即使存储它们也是不可能的。 这立即排除了任何显式构建或排序所有区间总和的方法。 

一个天真的错误是假设前缀和并直接对差异进行排序。 这仍然需要生成所有前缀索引对，这又是二次的。 另一个微妙的失败案例是试图通过扩展间隔来维护一堆子数组和，这仍然退化为二次行为。 

例如，如果数组是$[1, 2, 3]$，子数组和是$[1, 2, 3, 3, 5, 6]$。 正确的解决方案必须正确处理重复项，例如两次出现 3，这已经打破了简单化的“贪婪选择下一个扩展”的想法。 

## 方法

 暴力法很简单。 通过固定左端点并扩展右端点来计算每个子数组的总和，将所有总和累积到一个列表中，然后对列表进行排序并通过索引回答查询。 这是正确的，因为它直接构造了我们需要的多重集。 然而，它执行$O(n^2)$子数组的构造和排序需要$O(n^2 \log n^2)$，即使对于中等程度的人来说，这也远远超出了限制$n$。 和$n = 2 \times 10^5$，仅子阵列的数量就使得这种方法不可行。 

关键的观察是我们不需要显式地构造或排序所有总和。 相反，我们可以提出一个决策问题：给定一个值$x$，有多少个子数组的总和小于或等于$x$？ 如果我们可以有效地计算它，那么我们就可以进行二分搜索$x$找到最小值，使得至少$k$子数组有和$\le x$。 这将问题从对巨大的隐式数组进行排序转变为对单调谓词进行重复计数。 

计数步骤变得高效，因为所有数组值都是非负的。 这确保了如果我们固定左边界，扩展右边界只会增加总和，因此我们可以在线性时间内维护一个具有两个指针的滑动窗口。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2 \log n^2)$|$O(n^2)$| 太慢了|
 | 二分查找+两个指针|$O(n \log S)$|$O(1)$| 已接受 |

 这里$S$是数组的总和，它限制了所有子数组的总和。 

## 算法演练

 我们将问题简化为使用答案空间上的二分搜索来回答子数组和上的多个 k 阶统计查询。 

1. 计算最大可能的子数组和，即数组的总和。 这成为二分搜索的上限。 下限为零。 
2. 定义函数`count(x)`返回有多少个子数组的总和小于或等于$x$。 该功能是该解决方案的核心。 
3. 计算`count(x)`使用两个指针。 维护滑动窗口$[l, r]$及其总和。 对于每个右端点$r$，增加总和。 如果总和超过$x$， 移动$l$向前直到总和再次有效。 在每个位置$r$，所有以$r$并从任意索引开始$[l, r]$是有效的，有贡献$r - l + 1$子数组。 这是可行的，因为所有数字都是非负数，因此缩小窗口永远不会增加总和。 
4. 对于每个查询$k$，对取值范围进行二分查找$[0, S]$。 在每个中点$mid$, 计算`count(mid)`。 如果至少是$k$，我们可以向左移动； 否则我们向右移动。 
5. 最终的二分查找结果是最小值，使得至少$k$子数组的总和小于或等于它，这正是$k$-第一个最小的子数组和。 

### 为什么它有效

 正确性取决于谓词“sum ≤ x 的子数组的数量”的单调性。 作为$x$增加，该计数永远不会减少，因为每个先前有效的子数组仍然有效。 这使得二分搜索在答案空间上有效。 

里面`count(x)`，正确性来自滑动窗口不变量，即在每一步，窗口$[l, r]$是最小左边界，使得窗口之和 ≤$x$。 因为所有元素都是非负的，所以扩展$r$只能增加总和，并且移动$l$只能减少它。 因此每个有效子数组结束于$r$正是那些之间开始的$l$和$r$，并且没有遗漏或重复计算有效的子数组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_subarrays_leq(arr, x):
    n = len(arr)
    l = 0
    s = 0
    res = 0
    for r in range(n):
        s += arr[r]
        while l <= r and s > x:
            s -= arr[l]
            l += 1
        res += (r - l + 1)
    return res

def solve():
    n = int(input().strip())
    arr = list(map(int, input().split()))
    q = int(input().strip())
    queries = [int(input().strip()) for _ in range(q)]

    total = sum(arr)

    def kth(k):
        lo, hi = 0, total
        ans = total
        while lo <= hi:
            mid = (lo + hi) // 2
            if count_subarrays_leq(arr, mid) >= k:
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1
        return ans

    for k in queries:
        print(kth(k))

if __name__ == "__main__":
    solve()
```功能`count_subarrays_leq`是推拉窗柜台。 关键的实施细节是维护`l`这样窗口总和永远不会超过`x`。 这保证了每次调用的线性复杂度。 

功能`kth`对可能的子数组和执行二分搜索。 上限被安全地设置为总和，因为没有子数组可以超过它。

 ## 边缘情况

 对于像这样的全零数组$[0, 0, 0]$，每个子数组的和都是0。计数函数`count(x)`返回任意子数组的完整数量$x \ge 0$，并且对于每个查询，二分搜索都会正确收敛到 0，因为 0 是唯一可能的值。 

对于像这样的严格递增数组$[1, 2, 3]$，子数组和全部不同或轻度重复，但仍然单调。 滑动窗口总是仅在必要时收缩，并且每个子数组在`count(x)`因为每个右端点都贡献一个连续的有效起始块。 

对于具有内部零的情况，例如$[1, 0, 1]$，像 1 这样的和在不同的子数组中出现多次。 该算法不区分结构，只区分和，因此重复项自然会包含在计数中，从而保留基于排名的查询的正确性。
