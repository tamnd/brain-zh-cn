 ## 解决方案
 ## 问题理解

 我们有一个离散时间排队系统，其中时间被划分为秒。 几秒钟后，新的人到达并加入队列的末尾。 每一秒结束时，都会有固定数量的人从队列前面进入并离开系统。 

我们还获得了到达事件的日志：在某些秒内，指定数量的人在该秒开始时加入队列。 另外，我们被告知，在观察者醒来的特定时刻，他看到的队列长度必须与声明的值匹配。 第一个任务是验证整个日志是否与从空队列开始的单个有效模拟一致。 

如果日志一致，我们就会考虑第二个目标。 观察者将通过将自己附着在某一秒到达的人后面来加入队列，这意味着他只能选择至少有一个人到达的时间。 对于每个这样的有效秒，他计算他需要等待多长时间才能被服务机制处理。 在他醒来的那一刻或之后的所有有效选择中，他选择了最短等待时间的一个。 如果多个选择给出的等待时间相同，他更喜欢后一秒。 

这些约束意味着事件数量足够大，以至于对所有候选加入时间的任何二次模拟都会太慢。 系统本身在时间上是线性的，因为每一秒只执行恒定量的工作：增加到达人数和减少固定数量的人员。 这立即表明对所有事件进行单一前向模拟是可行的，但对每个可能的加入时间从头开始重新模拟是不可行的。 

当人们试图贪婪地验证日志而不考虑一秒钟内操作的确切顺序时，就会出现微妙的失败情况。 到达发生在一秒的开始，而离开发生在一秒的结束。 如果这些错误地交换或合并，则即使到达和出发的总数全局匹配，唤醒时的队列大小也可能是错误的。 

另一个常见的陷阱出现在第二部分：观察者并不是简单地在选定的时间向队列大小添加一个。 他在该秒的所有到达者都已进入后加入，这意味着他的位置取决于该秒的完整到达批次，而不仅仅是秒前的队列大小。 

## 方法

 一种直接的方法是独立模拟每个候选人的加入时间。 对于至少一个人到达的每一秒，我们重新计算队列的完整未来演变，然后计算何时为观察者提供服务。 如果有 m 个这样的候选秒，并且时间线延长到 T 秒，这会导致 O(mT) 的复杂度，在大输入下会崩溃。 

关键的观察是队列演化独立于观察者。 一旦我们从时间 1 开始模拟一次系统，我们就知道每秒开始时的确切队列大小，以及服务后剩余的人数。 这个单次传递已经为我们提供了验证和评估每个可能的加入时间所需的一切。 

第二个见解是观察者的等待时间可以根据一秒开始时的状态在本地计算。 如果在第 t 时刻，到达后的队列大小为 Q，并且有 a_t 新人到达，则观察者的位置为 Q 加 a_t。 由于服务每秒移除固定的 k 人，因此等待时间完全由该位置通过上限划分来确定。 

因此，我们将问题分为两个线性传递：一个前向模拟用于验证日志和计算队列状态，另一个扫描有效到达时间以计算最佳加入时刻。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个候选人时间重新模拟 | O(mT) | O(1) | O(1) | 太慢了|
 | 单次模拟+扫描| O(T + m) | O(T)| 已接受 |

 ## 算法演练

 我们首先以秒的递增顺序重建时间线。 

1. 按时间对所有到达事件进行排序，因为它们可能尚未排序。 这确保我们可以按时间顺序处理系统。 
2. 维护一个表示当前队列大小的变量。 将其初始化为零。 
3. 从第 1 秒迭代时间到日志中出现的或验证所需的最长时间。 在每一秒，首先将计划于该秒到达的所有到达添加到队列中。 这模拟了到达发生在开始时的事实。 
4. 应用到达后，如果这一秒是唤醒时间，则记录队列大小。 我们将其与给定的观测值进行比较。 如果不同，则日志立即无效。 
5. 在第二秒结束时，从队列中删除最多 k 个人。 如果队列少于 k 人，则队列变空。 
6. 完成完整模拟后，如果唤醒观察从未匹配，或出现任何不一致（例如负队列大小或不可能的转换），我们将拒绝该日志。 

一旦验证通过，我们就计算最佳加入时间。 

1. 再次重建前缀状态，或者重用存储的状态（如果已保存）。 对于至少有一个人到达的每一秒 t，计算到达后的队列大小。 观察员将在到达批次的最后加入。 
2. 设 Q 为在时间 t 到达后的队列大小。 观察者的位置是 Q，因为他加入到所有到达者的后面。 将他的服务时间计算为 ceil(Q / k)，相当于 (Q + k - 1) // k。 
3. 跟踪所有有效 t 的最短等待时间。 如果两秒给出相同的等待时间，则选择较大的 t。 

### 为什么它有效

 正确性取决于一个简单的不变量：在每一秒开始时，模拟队列与日志所暗示的真实系统状态完全匹配，并且在每一秒结束时，恰好 k 个人被删除，除非剩下的人更少。 由于到达和离开在每一秒内严格分开，因此整数边界处的队列状态完全决定了所有未来的行为。 一旦此状态被修复，观察者的任何假设插入仅取决于该边界处的队列大小，而不取决于任何早期决策。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import defaultdict

def solve():
    s, q0 = map(int, input().split())
    m, k = map(int, input().split())

    events = defaultdict(int)
    times = set()

    for _ in range(m):
        t, a = map(int, input().split())
        events[t] += a
        times.add(t)

    if not times:
        # no arrivals, trivial case
        if q0 != 0:
            print("Wrong Record")
        else:
            print(s, 0)
        return

    max_t = max(max(times), s)

    q = 0
    ok = False

    best_time = -1
    best_wait = 10**30

    for t in range(1, max_t + 1):
        if t in events:
            q += events[t]

        if t == s:
            if q != q0:
                print("Wrong Record")
                return
            ok = True

        if t in events:
            # candidate joining time: after arrivals
            pos = q
            wait = (pos + k - 1) // k

            if wait < best_wait or (wait == best_wait and t > best_time):
                best_wait = wait
                best_time = t

        q -= k
        if q < 0:
            q = 0

    if not ok:
        print("Wrong Record")
        return

    print(best_time, best_wait)

if __name__ == "__main__":
    solve()
```模拟严格按照时间顺序驱动。 每一秒都从应用到达开始，这是必要的，因为验证和观察者的决策都取决于到达后队列的大小。 唤醒检查在到达后立即执行，以便与声明中描述的完全匹配。 

候选人评估被嵌入到同一次扫描中。 观察者的位置被视为到达后的完整队列，因为他在那一刻加入。 等待时间是使用整数上限除法计算的，它直接对应于到达他的位置之前需要多少个大小为 k 的批次。 

取出后必须注意夹住队列； 如果没有这个，负值就会累积并悄悄地腐蚀以后的状态。

 ## 边缘情况

 当同一秒发生多个到达事件时，就会出现一种边缘情况。 这些必须在模拟之前合并； 否则，队列更新顺序会不一致。 该算法通过在以时间为键的字典中累积事件来处理此问题。 

另一种情况是在服务期间队列变得小于k。 正确的行为是将其限制为零而不是允许负值。 模拟在每次减法后明确强制执行此操作。 

最后一个微妙的情况是观察者的最佳选择正好发生在醒来的那一刻。 由于仅在有到达时才允许加入，因此唤醒秒仅在包含到达时才有效。 该算法自然地通过仅考虑事件时间来强制执行这一点。
