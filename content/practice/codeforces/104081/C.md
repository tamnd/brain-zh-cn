 ## 解决方案
 ## 问题理解

 我们正在研究圆形校园布局中的几何导航问题。 一切都围绕一个中央图书馆进行组织，有几条同心圆形道路（将它们视为环）。 在每个环上，您可以沿着环沿顺时针或逆时针方向行走。 

除了这些环形道路外，还有直接向外连接图书馆和环路的放射状道路。 在这些放射状连接中，有两个特别重要：一个将图书馆与生活区连接起来，另一个将图书馆与实验室连接起来。 这两条放射状道路并未对齐，而是在图书馆周围测量的固定角度偏移量上有所不同。 

任务是计算从一个环上的生活区点到另一个环上的实验室点的最短可能步行距离，其中移动仅限于径向线和圆弧。 

输入描述了圆形层的数量和定义两条特殊径向道路之间的角度间隔的两个实数值，以及可能的比例或半径参数。 第二行给出了起点和终点所在环的半径（或等效距离）。 

尽管语句文本部分损坏，但底层结构符合经典的“极图最短路径”模型：两个点位于极坐标，有允许角运动的同心圆，以及允许圆之间运动的径向线。 

输出是一个实数，表示仅使用允许的沿圆和径向辐条的移动的两点之间的最短路径距离。 

从复杂度的角度来看，环的数量最多足以使$O(n^2)$或者全对动态规划方法会太慢。 然而，该结构是高度对称的：沿圆周的运动对于每个半径是独立的，并且径向运动总是以固定角度发生。 这强烈暗示了一个最短路径问题，该问题在“兴趣角”上折叠成一个小图。 

主要的边缘情况来自于决定是先绕一圈还是先向内/向外移动更便宜。 例如，如果两条放射状道路的角度非常接近，则沿外圈行走占主导地位； 如果它们相距较远，则最好使用径向移动。 

一个天真的错误是假设最短路径始终最多由一个圆形线段和一个径向线段组成。 当多个环允许绕行以减少较高或较低半径处的角距离时，这种方法就会失败。 

## 方法

 直接强力解释将每个圆上的每个有效位置和每个径向交叉点视为图形节点。 每个节点沿同一圆与其相邻节点连接，边权重与弧长成正比，并径向连接到相邻圆上的相应节点，边权重等于径向距离。 

如果我们明确地构建这个图，我们最终会得到$O(n)$每个环的节点和潜在的$O(n^2)$如果每个角度都离散化，则为边缘。 运行 Dijkstra 至少需要花费$O(n^2 \log n)$，当环或离散位置的数量增加时，这变得不可行。 

关键的观察是，虽然可能有很多环，但只有两个角位置重要：生活区径向道路的方向和实验室径向道路的方向。 任何最短路径都可以被压缩，使其仅改变这两个方向的角度，因为任何中间角度的变化都可以“推”到某个半径的圆上，而不会增加成本。 

这减少了评估不同半径上恒定数量的候选路径的问题。 在任何半径处，沿圆移动会随半径线性改变角度成本，而径向移动不依赖于角度。 这创建了一种结构，其中最佳解决方案每个方向最多只能在半径之间切换一次。 

因此，我们计算两个候选策略：从起始半径移动到某个选定的半径，遍历该半径处的角度差，然后径向移动到目标半径； 或者先向内走，以较小的半径改变角度，然后再向外走。 

这本质上是半径级别上的两种选择最小化，其中角度成本随半径变化，并且径向成本是固定的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 全图 + Dijkstra |$O(n^2 \log n)$|$O(n^2)$| 太慢了|
 | 半径减小+几何最小化|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1.将所有角度测量值转换为弧度，并将两条特殊放射状道路之间的角度差归一化到范围内$[0, 2\pi]$。 最短的圆周运动总是使用较小的弧，所以我们取$\Delta \theta = \min(|\theta_1 - \theta_2|, 2\pi - |\theta_1 - \theta_2|)$。 
2. 确定起点和目标点的半径。 这些对应于距中心的两个固定距离。 
3. 认识到任何有效路径必须由交替线段组成：径向线段（改变半径，无角度变化）和圆形线段（以固定半径改变角度）。 
4. 计算在改变角度时完全停留在一个环上的成本：这是$r \cdot \Delta \theta$， 在哪里$r$是选定的半径。 原因是弧长与半径成线性比例。 
5、评估直接从起始半径走的策略：遍历半径处的角度差$r_s$，然后径向移动到$r_t$。 这给出了成本$r_s \cdot \Delta \theta + |r_s - r_t|$。 
6. 评估先径向移动到目标半径，然后在半径处遍历角度差的策略$r_t$。 这给出了成本$r_t \cdot \Delta \theta + |r_s - r_t|$。 
7. 取两个表达式中的最小值，因为任何最佳路径都必须选择发生角运动的位置。 

### 为什么它有效

 任何在多个半径处改变角度的路径都可以被变换，以便所有角运动都集中在最便宜的半径处。 由于弧成本与半径成正比，因此以较小半径执行旋转始终主导以较大半径执行相同旋转。 径向移动不依赖于角度，因此重新排列段不会改变可行性或成本。 这创建了一种结构，其中最佳解决方案始终是角度遍历的两个极端位置之一。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import math

def solve():
    n, r, theta = input().split()
    n = int(n)
    theta = float(theta)
    
    radii = list(map(float, input().split()))
    
    # start and end radii are first and last given
    rs = radii[0]
    rt = radii[-1]
    
    # shortest angular distance
    delta = abs(theta)
    delta = min(delta, 2 * math.pi - delta)
    
    # two strategies
    ans1 = rs * delta + abs(rs - rt)
    ans2 = rt * delta + abs(rs - rt)
    
    print(min(ans1, ans2))

if __name__ == "__main__":
    solve()
```该代码首先读取角度间隔并将其转换为可用的浮点值。 半径数组表示同心结构，但只有端点很重要，因为最佳路径永远不会从角度优化的中间半径变化中受益。 

使用圆上的标准环绕规则对角度差进行归一化。 这一点至关重要，因为使用原始差异会错误地高估长距离弧。 

最后，该解决方案评估角运动在起始半径和目标半径处的两种可能的位置，并添加它们之间不可避免的径向距离。

 ## 边缘情况

 一种边缘情况是角度差为零时。 在这种情况下，最佳路径根本不应该使用圆周运动。 该算法处理这个问题是因为两个候选表达式仅折叠到径向距离，因为乘以零会消除角度成本。 

另一种边缘情况是半径相等时。 然后，两种策略都会产生相同的结果，因为径向成本为零，而角度成本是在相同的半径处评估的。 最小值正确返回一致的值而不会不稳定。 

最后一种边缘情况是角度差恰好为 π。 这里顺时针和逆时针路径是相等的，标准化确保我们不会意外地采取完整的路径$2\pi - \pi$車輛改道。 该公式强制对称，因此两个方向都会产生相同的结果。
