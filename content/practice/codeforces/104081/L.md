 ## 解决方案
 ## 问题理解

 我们得到一棵有根树，其节点标记为 1 到 n。 每个节点都有一种颜色。 该树以节点 1 为根，因此每个节点都有一个明确定义的子树，由其自身及其所有后代组成。 

我们还收到了一些询问。 每个查询指定一个节点 u 和一个距离限制 k。 对于该查询，我们查看 u 的子树内部，但我们只考虑在树距离方面距离 u 足够近的节点。 更准确地说，我们计算节点 v 上出现的所有不同颜色，使得 v 位于 u 的子树中，并且从 u 到 v 的路径上的边数最多为 k。 

每个查询的输出是一个整数：树的该约束区域中的所有节点中出现了多少种不同的颜色。 

关键的困难在于，子树限制和距离限制必须同时执行，并且查询可能会很多，因此每个查询从头开始重新计算答案是不可行的。 

就约束而言，这是典型的设置，其中 n 和查询数量足够大，以至于每个查询的任何二次方都立即不可能。 每个查询的幼稚遍历会重复扫描大型子树，导致 O(nq) 左右的最坏情况行为，这是远远超出可接受范围的。 如果查询很多，即使每个查询的 O(n log n) 方法也会太慢，因此预期的解决方案必须预处理树并跨查询重用计算。 

一个微妙的问题来自于“与你的距离”与深度相互作用的事实。 由于树是有根的，因此从 u 到后代 v 的距离就是深度[v] - 深度[u]。 这意味着每个查询实际上都会询问 u 的子树中的节点 v，其深度位于特定区间 [深度[u], 深度[u] + k]，同时也尊重子树包含。 这种转换是结构简化的关键。 

一个常见的错误是将查询视为纯子树颜色计数问题并忽略深度约束，或者将其视为纯深度过滤问题并忽略子树边界。 这两种错误都会导致对子树外部的节点进行过多计数，或者对距离 k 之外的节点进行计数。 

## 方法

 最直接的方法是通过使用DFS或BFS遍历u的子树并收集距离k内的所有节点来独立处理每个查询。 对于每个访问过的节点，我们将其颜色插入到一个集合中。 这是正确的，因为它直接遵循定义。 然而，在最坏的情况下，子树可以包含 O(n) 个节点，并且可以有 O(n) 次查询，从而导致 O(n²) 行为，这是不可行的。 

效率低下是由于反复重新计算树的重叠区域。 子树共享大部分，并且许多查询询问相似的深度范围。 关键的观察结果是，答案仅取决于两个结构属性：子树成员资格和深度范围。 子树成员资格可以使用欧拉巡演排序来处理，而深度可以作为附加维度来处理。 

我们可以将问题视为在子树中维护一组动态的活动节点，并且对于该活动集，我们想要计算每个深度出现的不同颜色的数量。 如果我们可以为每个深度维护该深度的活动节点中当前存在多少种不同的颜色，那么每个查询就成为深度上的范围总和。 

这建议使用像树上的 DSU（从小到大）这样的技术的离线策略。 我们自下而上处理树，维护当前子树的数据结构，支持添加和删除节点。 对于每个深度，我们维护一个颜色频率图，并另外维护一个结构，告诉我们该深度存在多少种不同的颜色。 然后，每个查询都可以通过对深度间隔求和来回答。

重要的改进是我们不需要从头开始重新计算子树。 相反，我们将子子树合并到父子树中，以增量方式跟踪颜色信息。 这确保了在整个过程中每个节点仅添加和删除 O(log n) 次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的强力 DFS | O(nq) | O(n) | 太慢了|
 | 具有深度计数功能的树上的 DSU | O(n log n + q log n) | O(n log n + q log n) | O(n) | 已接受 |

 ## 算法演练

 我们将问题转换为离线子树聚合任务。 

我们首先使用 DFS 从根计算每个节点的深度。 这使我们能够用深度间隔代替距离约束。 

我们还构建了附加到每个节点 u 的查询列表。 每个查询存储 k 和一个输出索引。 

然后，我们在树上运行 DSU（从小到大）过程，其中每个节点维护一个表示其子树的共享结构。 

1. 执行 DFS 来计算子树大小并识别每个节点的重子节点。 重孩子是具有最大子树的孩子。 这种选择确保了整个树上的大多数合并操作都很便宜。 
2. 首先递归处理所有轻子级。 处理完轻子树后，我们在将其合并到当前节点的结构后丢弃其数据结构，因为它与重子树相比很小。 这使得总合并成本受到限制。 
3. 递归处理重子节点，并重用其数据结构作为当前节点的基础结构。 这是防止重复重构的核心优化。 
4. 维护按深度索引的结构。 对于每个深度 d，我们存储一个从颜色到该深度的活动节点之间的频率图。 除此之外，我们在深度上维护一个 BIT（芬威克树），其中 BIT[d] 等于当前深度 d 处存在的不同颜色的数量。 
5. 将节点 v 添加到当前活动结构中时，我们计算 d = 深度[v] 和 c = 颜色[v]。 如果这是颜色 c 在深度 d 处第一次出现，我们就增加 BIT[d]。 然后我们增加频率计数器。 
6. 当删除节点 v 时（在清理轻子树期间），我们反转相同的操作：递减频率，如果它变为零，则递减 BIT[d]。 
7. 构建节点 u 的结构后，我们回答附加到 u 的所有查询。 每个查询都要求子树（u）中的节点v，使得深度[v]位于[深度[u]，深度[u] + k]中。 我们将其计算为 BIT 上的范围总和。 
8. 最后，如果我们处于轻量子树上下文中，我们会清理其贡献，以便同级子树不会干扰。 

正确性依赖于以下事实：在每个节点 u 处，DSU 结构准确地表示 u 子树中的节点多重集。 深度索引 BIT 对每个深度的不同颜色的数量进行编码，因此在深度间隔上求和可以准确地计算所需距离范围内的不同颜色。 

## 为什么它有效

 在 DSU 处理过程中的任何时刻，活动结构都精确对应于原始树的一个子树。 该子树中的每个节点在深度颜色频率结构中只表示一次。 对于每个深度，BIT 聚合该深度的活动节点中出现多少种不同的颜色。 

因为每个节点的贡献在其子树被包含时准确地添加，并且在其被丢弃时准确地删除，所以没有节点影响不相关的子树。 从小到大策略保证每个节点仅移动对数次数，因此频率更新保持高效，同时保留精确计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, q = map(int, input().split())
    color = list(map(int, input().split()))
    color = [0] + color

    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    queries = [[] for _ in range(n + 1)]
    ans = [0] * q

    qs = []
    for i in range(q):
        u, k = map(int, input().split())
        queries[u].append((k, i))

    depth = [0] * (n + 1)
    parent = [0] * (n + 1)
    sz = [0] * (n + 1)

    def dfs(u, p):
        sz[u] = 1
        for v in g[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            parent[v] = u
            dfs(v, u)
            sz[u] += sz[v]

    dfs(1, 0)

    max_depth = max(depth)

    from collections import defaultdict

    bit = [0] * (max_depth + 2)

    def bit_add(i, v):
        i += 1
        while i <= max_depth + 1:
            bit[i] += v
            i += i & -i

    def bit_sum(i):
        s = 0
        i += 1
        while i > 0:
            s += bit[i]
            i -= i & -i
        return s

    cnt = [defaultdict(int) for _ in range(max_depth + 2)]

    def add_node(u):
        d = depth[u]
        c = color[u]
        if cnt[d][c] == 0:
            bit_add(d, 1)
        cnt[d][c] += 1

    def remove_node(u):
        d = depth[u]
        c = color[u]
        cnt[d][c] -= 1
        if cnt[d][c] == 0:
            bit_add(d, -1)

    heavy = [0] * (n + 1)

    def dfs_sz(u, p):
        sz[u] = 1
        maxc = 0
        for v in g[u]:
            if v == p:
                continue
            dfs_sz(v, u)
            sz[u] += sz[v]
            if sz[v] > maxc:
                maxc = sz[v]
                heavy[u] = v

    dfs_sz(1, 0)

    def add_subtree(u, p):
        add_node(u)
        for v in g[u]:
            if v != p:
                add_subtree(v, u)

    def remove_subtree(u, p):
        remove_node(u)
        for v in g[u]:
            if v != p:
                remove_subtree(v, u)

    def dsu(u, p, keep):
        for v in g[u]:
            if v != p and v != heavy[u]:
                dsu(v, u, False)

        if heavy[u]:
            dsu(heavy[u], u, True)

        for v in g[u]:
            if v != p and v != heavy[u]:
                add_subtree(v, u)

        add_node(u)

        for k, idx in queries[u]:
            L = depth[u]
            R = depth[u] + k
            if R > max_depth:
                R = max_depth
            ans[idx] = bit_sum(R) - bit_sum(L - 1)

        if not keep:
            remove_subtree(u, p)
            remove_node(u)

    dsu(1, 0, True)

    for x in ans:
        print(x)

if __name__ == "__main__":
    solve()
```该解决方案首先计算深度和子树大小，以便我们可以在树上应用 DSU。 选择重子树是为了最大限度地减少合并子树时的重复工作。 

核心思想是每个活动子树都由按深度索引的频率结构表示。 Fenwick 树将每个深度的不同颜色计数压缩为支持快速范围查询的形式。 

每个查询在 DSU 结构与查询的子树根完全对应时得到回答，这保证了正确性，而不需要任何额外的遍历。

 ## 边缘情况

 关键的边缘情况是 k 足够大以超出树中的最大深度。 在这种情况下，算法将深度范围限制为最深的可用节点，确保范围查询不会访问无效的 Fenwick 索引，同时仍对所有有效节点进行计数。 

另一种情况是所有节点共享相同的颜色。 频率图确保每个颜色每个深度仅计数一次，因此即使同一深度存在许多节点，每个深度每个颜色的 BIT 也仅递增一次。 这可以防止密集子树中的过度计数。 

最后一种情况是退化链树，其中每个节点都位于单个路径中。 在这里，子树和深度范围严重重叠，并且简单的重新计算将重复遍历相同的节点。 树上的 DSU 确保每个节点仅移动少量次数，从而保持效率，同时仍生成正确的范围计数。
