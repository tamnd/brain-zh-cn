 ## 解决方案
 ## 问题理解

 我们有一排人，每个人都有固定的权重，还有一个反复比较排在前面的人的游戏。 每轮比赛中，队列中的前两名选手进行比赛。 较重的一方赢得这一轮。 获胜者保持在前面并继续在以后的回合中竞争，而失败者则被发送到队列的后面。 我们还跟踪连续获胜：每当有人赢得一轮比赛时，他们当前的连胜次数就会增加，当任何参与者达到所需的连续获胜次数时，游戏立即结束，并且该参与者被宣布为总获胜者。 

输入给出了队列的初始顺序以及结束游戏所需的连续获胜次数。 输出是最终获胜者在原始排序中的位置。 

驱动该解决方案的关键约束是，如果直接模拟，队列可能会演化大量轮次。 每轮的时间复杂度为 O(1)，但在最坏的情况下，我们可以在确定获胜者之前执行大量交换和比较，特别是如果强有力的候选者从很早开始的话。 这排除了任何重复模拟整个过程而不深入了解其长期行为的方法。 

一个微妙的边缘情况来自连续获胜的定义。 如果将这一过程解释为需要显式模拟所有参与者的连续重置，则很容易使状态变得过于复杂。 另一个陷阱是假设获胜者可能取决于队列中的早期随机交互； 实际上，该过程具有确定性的主导因素。 

## 方法

 直接模拟遵循字面上的规则。 我们维护一个队列，重复弹出前两个元素，比较它们的权重，并将失败者推到后面。 我们还维护了当前连胜的地图。 每当有人获胜时，他们的连胜纪录就会增加，而对手的连胜纪录就会重置。 一旦任何连续达到所需的阈值，我们就会停止。 

这种方法是正确的，因为它准确地反映了该过程。 然而，它可能会严重降解。 如果最强的人从后面开始，他们可能需要循环通过许多对手才能到达前面。 每次交互都是恒定时间，但交互总数可能会变得非常大，使得这种方法对于大量输入来说可能太慢。 

关键的观察结果是该过程由全局最大权重主导。 任何比最大值弱的人都永远无法击败它，一旦最大值到达队列的前面，它就会在随后的每一轮中获胜。 从那一刻起，它的连胜次数就会确定性地增加，直到达到所需的阈值。 因此，整个过程只取决于最大元素何时到达前面，而不取决于中间比较的完整顺序。 

这将问题简化为查找初始数组中最大元素的索引。 该元素保证最终能够积累所需的连续胜利。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 全模拟 | O(n + 操作) 可能非常大 | O(n) | 太慢了|
 | 最大元素观察| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们通过识别不可避免地主导所有比较的元素来解决问题。 

1. 扫描权重列表，同时跟踪最大值及其在原始数组中的位置。 位置就是我们最终需要输出的位置。 
2. 每当我们看到大于当前最大值的值时，我们都会更新最大值及其索引。 这确保我们始终记住全球最强的参与者。 
3. 扫描完成后，我们返回存储的最大元素的索引作为答案。 

### 为什么它有效

该过程仅比较相邻元素，但任何弱于全局最大值的元素永远无法消除它。 一旦通过反复轮换最大值到达队列的前面，没有其他元素可以击败它，因此它将无限地累积胜利。 由于所有其他参与者最终都必须在直接比较链中输给它，因此保证连胜不间断增长的第一个要素是全局最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

max_val = -10**18
max_idx = -1

for i, v in enumerate(a, 1):
    if v > max_val:
        max_val = v
        max_idx = i

print(max_idx)
```该实现只是跟踪最大值，同时保留其原始的 1 索引位置。 第二个参数`k`不会影响最终结果，因为一旦最大元素占据了队列的前面，它最终将达到任何所需的连续获胜阈值。 

这里的一个常见错误是尝试显式模拟队列动态。 这会导致不必要的复杂性，并掩盖了获胜者的身份从一开始就固定的事实。 

## 工作示例

 考虑一个输入，其中权重为`[1, 3, 2, 5, 4]`。 最大值为`5`，位于位置`4`。 无论中间比较如何，其他所有元素最终都会输给`5`，一旦在前线活跃起来，就会不断获胜。 

| 步骤| 电流最大值 | 最大索引|
 | --- | --- | --- |
 | 1 | 1 | 1 |
 | 2 | 3 | 2 |
 | 3 | 3 | 2 |
 | 4 | 5 | 4 |
 | 5 | 5 | 4 |

 该迹线表明，只有全局最大值才重要，早期的局部最大值不会影响最终结果。 

再举个例子，`[7, 1, 6, 2]`，最大值已经在前面了。 答案就是立即索引`1`，队列中的任何交互都无法改变这一点。

 该解决方案很容易满足约束条件，因为它对输入执行单个线性扫描。 

## 测试用例```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    mx = -10**18
    idx = -1
    for i, v in enumerate(a, 1):
        if v > mx:
            mx = v
            idx = i
    return str(idx)

# sample-like checks
assert solve("6 3\n1 1 4 5 1 4\n") == "4"

# minimum size
assert solve("1 10\n5\n") == "1"

# already maximum at front
assert solve("4 2\n9 1 2 3\n") == "1"

# maximum at end
assert solve("4 2\n1 2 3 9\n") == "4"

# all equal
assert solve("5 100\n7 7 7 7 7\n") == "1"
