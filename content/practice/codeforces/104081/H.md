 ## 解决方案
 ## 问题理解

 给我们一个带权无向图和一个想要从固定起始节点移动到固定目的地节点的旅行者。 每条边都有一个行程时间。 除了边缘成本之外，每个节点还具有关联的“任务时间”，该时间是旅行者经过该节点时产生的。 

不同的是，旅行者可以忽略沿途有限数量的节点的任务成本。 每个查询都提供一个限制，描述可以跳过多少个节点任务，并且还提供该特定场景的节点任务成本。 对于每个查询，我们必须计算从起始节点到目标节点的最小可能总时间，其中总时间是边权重加上所有访问节点的节点成本之和，除了固定数量的可以跳过成本的节点。 

输入结构是一个静态图，后面跟着多个独立的查询。 每个查询有效地重新定义节点成本以及可以忽略成本的节点数量。 

从复杂性的角度来看，图可能足够大，以至于任何为没有结构的状态重新计算朴素最短路径的方法都会太慢。 Codeforces 图的典型约束机制意味着每个查询的解决方案必须围绕$O((n+m)\log n)$或更好，或者重用具有较小乘法因子的共享最短路径框架。 由于每个查询都会引入一个新的优化维度（最多跳过 k 个节点成本），因此我们需要在扩展的状态空间上使用最短路径算法。 

一种简单的方法会尝试枚举所有可能的节点子集，其成本沿着每条路径被跳过。 这会立即失败，因为子集的数量随路径长度呈指数增长。 

一种更微妙的错误方法是计算忽略节点成本的最短路径，然后减去该路径上的 k 个最大节点成本。 这会失败，因为最佳路径本身取决于您选择跳过的节点。 选择不同的路径可能会产生一组更好的“可跳过”节点。 

例如，考虑两条路线：一条路线具有较小的边缘成本，但许多小节点成本，而另一条路线具有较大的边缘成本，但昂贵的节点成本较少。 最佳选择取决于 k，固定路径上的局部调整无法捕捉到这种相互作用。 

## 方法

 蛮力观点是独立对待从源到目的地的每条路径。 对于每条路径，我们将尝试选择最多 k 个已删除成本的节点的所有方法，计算最终的总成本，并在所有路径上取最小值。 即使我们将自己限制在通常意义上的最短路径，图中可能的简单路径的数量也是指数级的，并且跳过节点上的每条路径组合增加了另一个指数因子。 即使对于很小的图，这很快也会变得不可行。 

关键的观察结果是，如果我们明确跟踪到目前为止已使用了多少次跳跃，则该问题具有最佳子结构。 一旦我们修复了一个节点和已使用的跳过计数，达到该状态的最佳方法并不取决于我们如何到达那里。 这建议将每个节点扩展为多个状态，表示已消耗了多少个节点成本跳过。 

我们不是解决单个最短路径问题，而是解决分层最短路径问题，其中每个节点$u$成为国家$(u, j)$， 在哪里$j$是迄今为止使用的跳过节点成本的数量。 从一个状态开始，当我们移动到邻居时，我们有两种选择：要么支付目标节点的节点成本，要么如果仍有剩余的跳过预算则跳过它。 这将问题转换为图上的标准最短路径$n \times (k+1)$状态，可以用 Dijkstra 算法解决。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 枚举所有路径并跳过子集 | 指数| 指数| 太慢了|
 | 在（节点，跳过使用的）状态上分层 Dijkstra |$O((n(k+1) + m(k+1)) \log (n(k+1)))$|$O(nk)$| 已接受 |

 ## 算法演练

 我们独立处理每个查询，并在扩展状态图上运行最短路径算法。 

1. 我们将状态定义为一对$(u, j)$， 在哪里$u$是当前节点并且$j$是已使用的节点成本跳过数量。 这种编码是必要的，因为未来的决策取决于还有多少个跳过可用。 
2.我们将除起始状态之外的所有距离初始化为无穷大$(1, 0)$，如果我们决定不跳过它，则其成本等于节点 1 的节点成本。 如果允许跳过，我们还考虑替代的初始状态$(1, 1)$如果 k 至少为 1，则节点成本为零。这确保从一开始就表示两种可能性。 
3. 我们在这些状态上使用优先级队列来运行 Dijkstra 算法。 每次我们提取一个状态$(u, j)$，我们尝试松弛所有边$(u, v)$。 
4. 当从$u$到$v$，我们考虑两种情况。 在第一种情况下，我们支付的节点成本为$v$，保持跳过计数不变并移动到$(v, j)$。 在第二种情况下，如果$j < k$，我们跳过节点成本$v$并移至$(v, j+1)$。 这种分支是对跳跃的有限预算进行建模的核心机制。 
5. 我们在两个转换中添加边权重成本，因为总是要支付遍历成本。 
6. 处理完所有状态后，答案是所有状态中的最小值$(n, j)$为了$0 \le j \le k$，因为使用最多 k 次的跳跃到达目的地都是有效的。 

### 为什么它有效

 原始问题中的每条有效路径都对应于扩展状态图中的一条路径，其中状态索引跟踪每一步使用了多少次跳过。 相反，扩展图中的每条路径都对应于原始图中的有效路线，并且具有一致的跳过节点选择。 由于 Dijkstra 算法总是找到具有非负权重的图中的最短路径，因此所有目标状态的最小值会产生最佳解决方案。 状态扩展保留了影响成本的所有决策，因此不排除任何最佳解决方案。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v, w = map(int, input().split())
        g[u].append((v, w))
        g[v].append((u, w))
    
    q_line = input().split()
    if not q_line:
        return
    k = int(q_line[0])
    
    # node costs
    cost = list(map(int, q_line[1:]))
    # adjust if input is 1-indexed or missing alignment
    if len(cost) != n:
        cost = cost[:n]
    
    dist = [[INF] * (k + 1) for _ in range(n + 1)]
    pq = []
    
    # start at node 1
    dist[1][0] = cost[0]
    heapq.heappush(pq, (dist[1][0], 1, 0))
    
    if k > 0:
        dist[1][1] = 0
        heapq.heappush(pq, (0, 1, 1))
    
    while pq:
        d, u, used = heapq.heappop(pq)
        if d != dist[u][used]:
            continue
        
        for v, w in g[u]:
            nd = d + w
            
            # pay cost
            if nd + cost[v - 1] < dist[v][used]:
                dist[v][used] = nd + cost[v - 1]
                heapq.heappush(pq, (dist[v][used], v, used))
            
            # skip cost
            if used < k:
                if nd < dist[v][used + 1]:
                    dist[v][used + 1] = nd
                    heapq.heappush(pq, (nd, v, used + 1))
    
    ans = min(dist[n])
    sys.stdout.write(str(ans))

if __name__ == "__main__":
    solve()
```该实现维护一个二维距离表，其中第二维跟踪已使用的节点成本跳过次数。 优先级队列总是扩展当前最便宜的已知状态，确保 Dijkstra 贪婪选择的正确性。 

一个微妙的细节是起始节点的初始化。 我们明确考虑支付和跳过节点 1 的成本，因为它也是路径的一部分。 错过这种分割会导致少算或多算，具体取决于解释。 

另一个重要的细节是沿边缘移动时正确索引节点成本。 由于节点在图中的索引为 1，而 Python 数组的索引为 0，因此成本查找必须始终从节点索引中减去 1。 

## 工作示例

 考虑一个小图，其中节点 1 连接到节点 2，节点 2 连接到节点 3。假设 k 为 1，节点成本为$[5, 10, 1]$，所有边权重都等于 1。 

我们跟踪状态$(node, used)$。 

| 步骤| 状态弹出 | 距离 | 过渡| 新状态 |
 | --- | --- | --- | --- | --- |
 | 1 | (1,0)| 5 | 前往2支付费用| (2,0)=1+5+10 |
 | 2 | (1,0)| 5 | 跳至2 跳过| (2,1)=1 | (2,1)=1 |
 | 3 | (2,1) | 1 | 前往3付| (3,1)=3 | (3,1)=3 |
 | 4 | (2,0) | 16 | 16 跳至3 跳过| (3,1)=2 |

 最好的结果是通过跳过昂贵的节点 2 来实现的，这说明了为什么状态跟踪是必要的。 

该跟踪显示了不同的跳过分配如何产生不同的最佳路径，以及为什么单个最短路径是不够的。

 ## 边缘情况

 一种边缘情况是 k 为零时。 在这种情况下，算法绝不能转变为“跳过”状态，并且所有答案都会减少到标准最短路径，并增加节点成本。 状态图正确地处理了这个问题，因为不可能转换到更高的跳过层。 

另一个边缘情况是当 k 足够大以跳过最佳路线上的每个节点时。 该算法沿着该路径自然地收敛到零节点成本贡献，因为只要有预算，它总是允许跳过。 正确性取决于保持单独的状态而不是贪婪地跳过早期节点。
