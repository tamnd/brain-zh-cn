 ## 解决方案
 ## 问题理解

 该问题描述了一个在离散时间内演变的过程，其中贡献出现，然后以非常特定的方式增长。 每时每刻都会引入一些新单位。 一旦引入，每个单元就不会保持不变：相反，其贡献在每个后续步骤中都会加倍。 

您将获得该系统在每个时间步的总观测值。 每个观测值都是迄今为止出现的所有单位贡献的总和，较旧的单位贡献更多，因为它们有更多的时间加倍。 任务是逆转这个过程，恢复每个时间步必须引入多少新单元，以便观察到的总数变得一致。 

输入可以被视为隐藏过程的聚合测量序列。 输出是另一个序列，代表每个时间步骤新贡献的“诞生”，从而解开重叠的指数增长。 

这些限制意味着对每个单位增长的简单模拟会太慢。 如果我们直接独立地模拟每个单元，则每个新单元都需要更新所有未来的时间步长，从而在最坏的情况下导致二次行为。 在典型的 Codeforces 限制下，一旦步数达到 10^5 左右，这立即变得不可行。 

第二个微妙的问题是贡献严重重叠。 将连续值之间的差异直接归因于新单位的天真贪婪尝试失败了，因为旧单位贡献的金额不断增加，而不是恒定的金额。 例如，如果观察到的序列以突然跳跃开始，则该跳跃可能来自新引入的单元和所有先前单元的加倍。 

一个小的具体失败案例有助于说明这一点。 假设观测值是：

 输入：

 t = [1, 2, 4]

 天真的方法可能会认为每一步都会增加 +1 个单位。 这表明出生 [1, 1, 1]，但会产生值 [1, 3, 7]，这不匹配。 出现不匹配的原因是先前的单位不断加倍，因此连续值之间的差异不是独立的。 

正确的解决方案必须隔离新引入的单元的确切贡献，同时取消早期步骤的指数进位。 

## 方法

 暴力重建将明确跟踪每一步引入的每个单元。 对于每个时间步长，我们都会迭代所有先前引入的单元，并通过加倍来更新它们的贡献，然后添加任何新单元。 这正确地模拟了该过程，但成本为 O(n^2) 操作，因为 n 个步骤中的每一个都可能更新所有先前的贡献。 当 n 达到 10^5 时，这远远超出了可行的限制。 

关键的观察结果是该过程是线性的并且遵循固定的递归。 每个先前存在的单元在每一步都会将其贡献加倍，这意味着总观测值满足连续状态之间的简单关系。 如果我们将时间 t 引入的新单元的数量表示为 b[t]，将观察到的总数表示为 f[t]，那么当从 t−1 移动到 t 时，每个先前的贡献都会乘以 2，然后添加 b[t]。 

这给出了直接关系：

 f[t] = 2 * f[t−1] + b[t]

 重新排列此表达式可隔离隐藏序列：

 b[t] = f[t] − 2 * f[t−1]

 这完全消除了跟踪个人贡献的需要。 一旦知道前一个值，就可以在恒定时间内计算每个值。 整个问题简化为对阵列的单个线性传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n^2) | O(n^2) | O(n) | 太慢了|
 | 线性重建 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 读取观测值 f[0..n−1] 的序列。 这些代表每个时间步长的累积贡献。 
2. 将第一个值 f[0] 视为全新的贡献，因为没有以前的历史记录。 这直接给出 b[0] = f[0]。 
3. 对于从 1 到 n−1 的每个后续索引 t，将先前状态的预期贡献计算为 2 * f[t−1]。 这代表了经过一次加倍步骤后的所有早期单元。 
4. 从当前观察值中减去预期结转贡献，以分离出新的贡献：

 b[t] = f[t] − 2 * f[t−1]
 5. 存储或输出每一步的b[t]。 一旦先前的观测值已知，每个值都是独立的。 

微妙之处在于，加倍统一适用于整个过去的状态，因此可以在全局范围内将其分解出来。 这就是减法能够完美消除所有历史重叠的原因。 

### 为什么它有效

 在每一步中，系统都会通过采用先前的总数并将其中的每个贡献加倍来发展。 这意味着整个过去的行为就像单个聚合数量乘以 2。之前加倍的总数与当前观测值之间的任何偏差都必须完全来自该步骤中新引入的单位。 由于加法是线性的，并且加倍分布在总和上，因此不会出现交互项，并且递归是精确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    f = list(map(int, input().split()))
    
    if n == 0:
        return
    
    b0 = f[0]
    print(b0, end=" ")
    
    prev = f[0]
    for i in range(1, n):
        cur = f[i] - 2 * prev
        print(cur, end=" ")
        prev = f[i]

if __name__ == "__main__":
    solve()
```该解仅保留先前的观测值，因为递归仅取决于 f[t−1]。 每一步都会在恒定时间内计算新的隐藏值。 第一个元素是单独处理的，因为没有较早的状态可供减去。 

一个常见的实施陷阱是更新`prev`错误地。 它必须存储观测值`f[t]`，不是重构值`b[t]`，因为重复率是根据观察到的总数定义的。 

另一个微妙的问题是整数大小。 由于重复加倍，值可能会快速增长，因此使用 Python 整数是安全的，但在更严格的语言中，这需要 64 位或更高版本。

 ## 边缘情况

 一个关键的边缘情况是序列完全遵循指数倍增，并且在第一步之后没有新的插入。 对于输入：```
3
1 2 4
```该算法计算 b[0] = 1，然后 b[1] = 2 − 2·1 = 0，并且 b[2] = 4 − 2·2 = 0。这证实了一旦设置了初始状态，系统就会在没有额外贡献的情况下演化，并且递归会干净地产生零。 

当每一步都引入新的贡献时，就会出现另一种边缘情况，从而创建一个快速增加的序列。 为了：```
3
1 3 8
```我们得到 b[0] = 1，b[1] = 3 − 2·1 = 1，b[2] = 8 − 2·3 = 2。向前追踪显示每个重构的加法与超出加倍的多余部分完全匹配，证实重叠指数增长不会干扰增量的隔离。
