 ## 解决方案
 ## 问题理解

 我们有两个数组，`a`和`b`, 两者的长度`n`。 我们可以执行操作`a`每个索引最多一次：对于任何索引`i`从 1 到`n-1`，我们可以设置`a[i]`到`a[i] XOR a[i+1]`。 问题是是否有可能通过选择一系列此类操作来转换`a`完全进入`b`。 

输入由多个测试用例组成。 每个测试用例提供了大小`n`和两个数组`a`和`b`。 如果转换可能，我们需要输出“YES”，否则输出“NO”。 

这些约束意味着我们需要一个大致线性的算法`n`对于每个测试用例，因为`n`最大可达 2·10^5，并且`n`所有测试用例的范围也以 2·10^5 为界。 尝试所有操作序列的简单解决方案是指数级的，这太慢了。 我们必须推理问题的结构，而不是模拟每一个操作。 

边缘情况包括带有零的数组、仅最后一个元素不同的数组或以下情况`a`已经等于`b`。 例如，如果`a = [0,0,1]`和`b = [0,0,0]`，一种天真的贪婪方法可能会尝试对第一个元素进行异或，但会错过任何允许的操作序列都无法删除尾随的元素`1`。 

## 方法

 蛮力方法很简单：对于每个索引`i`，尝试执行 XOR 运算`i+1`并递归检查是否`b`可以得到。 这在原则上是正确的，因为每个允许的操作都会被考虑，但它会导致 O(2^n) 的可能性，并且对于`n`最多 2·10^5。 

实现线性解决方案的关键观察是查看之间的异或差异`a`和`b`。 让`d[i] = a[i] XOR b[i]`。 每次操作`a[i] := a[i] XOR a[i+1]`切换`d[i]`经过`a[i+1]`。 因为我们只能从左到右进行操作，并且每个索引仅受其前一个元素影响一次，所以我们可以贪婪地传播 XOR 校正：`a[i]`不匹配`b[i]`，我们必须在`i`来调整它。 唯一需要注意的是最后一个元素无法更正，因为没有`a[n+1]`。 这给出了关键的见解：当且仅当最后一个元素匹配并且传播的校正不与先前设置的元素冲突时，转换才是可能的。 

这种见解将问题简化为从左到右的单个传递，维护差异数组并根据需要应用操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 贪婪传播 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，计算差异数组`d[i] = a[i] XOR b[i]`。 
2. 从左到右迭代索引`i = 0`到`n-2`。 在每个索引处，如果`d[i] != 0`，我们必须在`i`。 更新`d[i+1] := d[i+1] XOR d[i]`并设置`d[i] := 0`。 这对应于应用`a[i] := a[i] XOR a[i+1]`。 
3. 迭代结束后，检查`d[n-1]`。 如果`d[n-1] == 0`，输出“是”； 否则，输出“NO”。 最后一个元素无法调整，因此不匹配意味着无法进行转换。 

为什么它有效：不变的是处理索引后`i`，所有差异`d[0]..d[i]`已修正为零。 将所需的 XOR 传播到`d[i+1]`这正是该操作的作用。 这保证了如果最后一个差值变为零，则`a`匹配`b`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can_transform(a, b, n):
    d = [a[i] ^ b[i] for i in range(n)]
    for i in range(n - 1):
        if d[i]:
            d[i+1] ^= d[i]
            d[i] = 0
    return d[-1] == 0

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    print("YES" if can_transform(a, b, n) else "NO")
```该代码首先计算之间的异或差异`a`和`b`。 然后它从左到右扫描，通过将差异传播到下一个元素来将差异归零。 循环结束后，如果最后一个元素的差异为零，则可以进行转换。 需要仔细注意最后一个元素和索引：该操作仅影响`i`和`i+1`，所以我们从不尝试`i = n-1`。
