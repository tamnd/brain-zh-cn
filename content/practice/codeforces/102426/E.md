 ## 解决方案
 ## 问题理解

 我们有一系列`n`正整数。 每对索引`l <= r`定义一个连续的子数组，其值是所有元素的总和`l`通过`r`。 正好有`n(n+1)/2`这样的子数组，等和是分开计算的，因为不同的子数组对应着不同的魔法结果。 

任务是找到`k`- 所有这些和按非递减顺序排序后的最小子数组和。 例如，与`2 3 1 4`，十个子数组产生排序序列`1, 2, 3, 4, 4, 5, 5, 6, 8, 10`， 所以`k = 6`给出`5`。 

数组长度可以达到`10^5`。 这意味着可以有大约`5 * 10^9`子数组。 即使每个子数组执行恒定工作的算法也已经太慢，并且在内存限制下显式存储所有子数组和是不可能的。 元素可以大到`10^9`，所以子数组的和可以达到大约`10^14`，这还需要在具有固定宽度整数的语言中进行 64 位整数算术。 

每个人的积极性`ai`是关键的结构性约束。 因此，前缀和严格递增，这让我们可以计算线性时间内最多有多少个子数组和是给定值。 如果没有积极性，两指针计数论证就行不通。 

有几种边界情况可能会悄无声息地破坏实现。 为了`n = 1`，唯一可能的结果是单个元素。 例如，`1 1`其次是`7`有答案`7`; 意外搜索空范围子数组的代码可能会在此处失败。 

相等的子数组和必须按重数进行计数。 为了`3 4`其次是`2 2 2`，排序后的总和是`2, 2, 2, 4, 4, 6`，所以答案是`4`。 将结果视为不同值的解决方案会错误地认为只有三种可能的结果。 

最小和最大可能的排名也很有意义。 为了`3 1`其次是`1 5 2`，最小的子数组和是`1`，同时对于`3 6`答案是整个数组的总和，`8`。 在计数函数中使用严格不等式的二分搜索可以在任一边界处偏离 1。 

## 方法

 直接的方法是枚举每个连续的子数组。 对于每个左端点，一次将右端点扩展一个位置并维持当前总和，给出每个子数组的总和`O(1)`额外的工作。 这是正确的，因为每对`(l, r)`恰好出现一次。 有`n(n+1)/2`这样的对，即`5,000,050,000`什么时候`n = 100000`。 仅仅生成这么多值就已经远远超出了时间限制，对它们进行排序会使情况变得更糟。 

蛮力方法之所以有效，是因为它显式地构造了一个集合，该集合的`k`- 我们想要的第一个元素。 问题在于集合本身的大小是二次方的。 观点的有用改变是停止询问每个子数组的总和，而是询问一个计数问题：给定一个数字`x`, 最多有多少个子数组有和`x`？ 

一旦计数操作很快，原来的选择问题就变成了二分搜索。 如果我们可以计算`count(x)`，子数组和的数量不大于`x`， 然后`count(x)`是单调的。 对于小`x`，很少有适合的金额； 作为`x`增加，计数只能增加。 答案就是最小的`x`为此`count(x) >= k`。 

计算`count(x)`，定义前缀和`p[0] = 0`和`p[i] = a1 + a2 + ... + ai`。 

子数组的和`l..r`是`p[r] - p[l-1]`。 因为数组的每个元素都是正数，`p`是严格增加的。 对于固定的右前缀索引`r`，我们需要`p[r] - p[i] <= x`这相当于`p[i] >= p[r] - x`。 

由于前缀和已经排序，我们可以找到第一个合适的`i`通过二分查找来查找每个`r`, 给予`O(n log n)`计数。 我们可以做得更好。 作为`r`向右移动，`p[r]`增加，所以阈值`p[r] - x`也增加。 第一个有效`i`永远不能倒退。 因此，单个移动指针会计算所有有效的起始位置`O(n)`时间。 

外部二分查找需要`O(log S)`迭代，其中`S`是数组总和。 自从`S <= 10^14`，这少于 50 次迭代。 由此产生的复杂度是`O(n log S)`，这对于`n = 10^5`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n² log n) | O(n² log n) | O(n²) | 太慢了|
 | 最佳 | O(n log S) | O(n log S) | O(n) | 已接受 |

 这里`S`表示整个数组的和。 

## 算法演练

 1.构建前缀和数组`p`。 放`p[0] = 0`， 然后`p[i] = p[i-1] + a[i]`。 因为所有`ai`是正数，前缀和严格递增。 
2. 定义函数`count(x)`返回总和最多为的连续子数组的数量`x`。 对于前缀索引表示的每个右端点`r`，我们需要计算所有`i < r`满意的`p[r] - p[i] <= x`。 
3. 将条件重写为`p[i] >= p[r] - x`。 维护一个指针`left`到满足此条件的第一个前缀和。 尽管`left < r`和`p[left] < p[r] - x`， 进步`left`。 
4. 指针停止后，每个前缀索引从`left`通过`r-1`给出一个结束于的有效子数组`r-1`。 有`r - left`其中，因此将该数字添加到计数中。 

指针永远不需要向后移动。 什么时候`r`增加，阈值`p[r] - x`增加是因为前缀和增加。 因此，已经太小的前缀和以后永远不会变得有效。 
5. 对两者之间的答案进行二分查找`1`和`p[n]`，数组总和。 对于中点`mid`, 计算`count(mid)`。 如果计数至少为`k`， 然后`mid`足够大以容纳`k`-最小的和，所以搜索左半部分。 否则，搜索右半部分。 
6. 二分查找结束后，下界为count达到的最小值`k`。 打印该值。 

### 为什么它有效

 对于每一个固定的`x`，计数函数考虑每个可能的右端点。 对于该端点，有效的左前缀索引形成早期前缀索引的一个后缀，因为前缀和正在增加。 移动指针标识该后缀的第一个成员，因此`r - left`精确计算以该处结尾的所有有效子数组。 因此`count(x)`恰好是最多子数组和的数量`x`。 

谓词`count(x) >= k`是单调的，因为增加`x`只能将额外的子数组和从太大变为有效。 因此二分查找找到最小值`x`至少含有`k`子数组求和。 由于子数组和是整数，因此该值恰好是`k`-第最小总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    prefix = [0] * (n + 1)
    for i in range(1, n + 1):
        prefix[i] = prefix[i - 1] + a[i - 1]

    total = prefix[n]

    def count_at_most(x):
        left = 0
        count = 0

        for right in range(1, n + 1):
            threshold = prefix[right] - x

            while left < right and prefix[left] < threshold:
                left += 1

            count += right - left

            if count >= k:
                return count

        return count

    lo = 1
    hi = total

    while lo < hi:
        mid = (lo + hi) // 2

        if count_at_most(mid) >= k:
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```前缀结构存储第一个的总和`i`位置上的元素`i`。 额外的零位于`prefix[0]`表示一个空前缀，对于从索引开始的子数组是必需的`1`。 

里面`count_at_most`,`right`是结束前缀索引。 相应的子数组在某个前缀索引之后开始`left`。 不平等`prefix[left] >= prefix[right] - x`正是结果子数组总和不超过的条件`x`。 

条件在`while`循环使用`<`， 不是`<=`。 如果`prefix[left] == prefix[right] - x`，结果子数组的总和正好`x`并且必须被计算在内。 排除等式会将函数变成严格小于的总和计数`x`，这会改变二分搜索的答案。 

这`left < right`条件防止在两侧使用相同的前缀索引，这将表示空子数组。 每个有效子数组都有一对不同的前缀索引`left < right`。 

早返时`count >= k`对于正确性来说不是必需的，但是一旦二分搜索已经知道这，它就可以避免扫描剩余的前缀和`x`足够大。 Python 整数自动处理超出 64 位范围的和，尽管实际约束只需要大约 64 位范围的值`10^14`。 

二分查找使用`lo = 1`因为每个数组元素都是正数，所以每个非空子数组都有正和。`hi = total`有效，因为整个数组本身具有该总和，并且它是最大可能的子数组总和。 

## 工作示例

 ### 示例 1

 对于输入`4 6`带数组`2 3 1 4`，前缀和是`0, 2, 5, 6, 10`。 正确答案是`5`。 

二分查找的有用部分可以如下追踪。 

|`lo`|`hi`|`mid`|`count(mid)`| 决定|
 | --- | --- | --- | --- | --- |
 | 1 | 10 | 10 5 | 6 |`6 >= 6`, 向左搜索 |
 | 1 | 5 | 3 | 3 |`3 < 6`, 向右搜索 |
 | 4 | 5 | 4 | 5 |`5 < 6`, 向右搜索 |
 | 5 | 5 | 5 | 6 | 停止|

 为了`x = 5`，六个符合条件的子数组是总和`1, 2, 3, 4, 4, 5`。 为了`x = 4`，只有五个子数组符合条件。 这证明`5`是包含至少六个结果的第一个阈值。 

### 自定义示例 2

 考虑：```
3 4
2 2 2
```前缀和是`0, 2, 4, 6`。 六个子数组的和是`2, 2, 2, 4, 4, 6`，所以第四个答案是`4`。 

为了`x = 3`，每个长度为一的子数组都有和`2`，而每个长度为二或长度为三的子数组都太大。 因此`count(3) = 3`。 

为了`x = 4`，三个长度为 1 的子数组和两个长度为 2 的子数组符合条件，给出`count(4) = 5`。 

|`lo`|`hi`|`mid`|`count(mid)`| 决定|
 | --- | --- | --- | --- | --- |
 | 1 | 6 | 3 | 3 |`3 < 4`, 向右搜索 |
 | 4 | 6 | 5 | 5 |`5 >= 4`, 向左搜索 |
 | 4 | 5 | 4 | 5 |`5 >= 4`, 向左搜索 |
 | 4 | 4 | 4 | 5 | 停止|

 答案是`4`。 此示例说明了为什么必须单独计算重复的总和。 价值`2`出现3次，其值`4`出现两次。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log S) | O(n log S) | 每个`count_at_most`呼叫动作`left`和`right`仅向前，因此成本为 O(n)，二分查找使用 O(log S) 调用。 |
 | 空间| O(n) | 前缀和数组包含`n + 1`价值观。 |

 和`n <= 10^5`和`S <= 10^14`，二分查找执行的计数次数少于 50 次。 每次传递都是线性的，因此该算法仅执行几百万次指针操作，而不是数十亿次子数组操作。 前缀数组还使用线性内存，只要小心一点，它就可以轻松地满足 Python 中规定的 64 MB 限制； 该实现仅存储输入数组和前缀数组，并且不存储子数组和的二次集合。

 ## 边缘情况

 对于单个元素，输入`1 1`其次是`7`仅给出一个前缀差异，`7 - 0 = 7`。 在计数过程中，`right = 1`和`left = 0`，因此计数变为`1`。 二分查找有`lo = hi = 7`，并立即返回`7`。 

对于重复的总和，请考虑`3 4`其次是`2 2 2`。 在`x = 3`，指针精确计算三个长度为 1 的子数组，给出`3`，即下面的`k = 4`。 在`x = 4`，两个长度为 2 的子数组也变为有效，因此计数变为`5`。 因此，至少有四个结果的最小阈值是`4`。 该算法从不删除重复的和，因此自然地保留了多重性。 

对于尽可能最小的排名，`4 1`其次是`5 1 3 2`具有最小子数组和`1`。 谓词`count(x) >= 1`首先变为真`x = 1`。 当计数达到时，二分查找保留下半部分`k`，所以它正好落在`1`。 

对于最大可能的排名，`4 10`其次是`5 1 3 2`要求第十个也是最后一个子数组的总和。 由于所有元素均为正数，因此完整数组的总和最大，`5 + 1 + 3 + 2 = 11`。 在`x = 10`，并非所有十个子数组都符合条件，而在`x = 11`，所有十个都这样做。 因此二分查找返回`11`。 

最大尺寸全 1 测试有`100000`元素和`k = n(n+1)/2`，所以请求的结果是最大的子数组和，即`100000`。 计数函数从不构造大约 50 亿个子数组。 它的指针只需在每次二分搜索迭代中前进一次前缀和，这说明了为什么可能结果的二次数并不强制采用二次算法。
