 ## 解决方案
 ## 问题理解

 我们有 (N) 个相同的圆形照明区域。 它们的中心位于一条笔直的街道上，连续的中心相距正好 (L) 个单位，每个圆都有半径 (R)。 任务是计算至少一盏灯覆盖的面积。 

这些圆圈排列成一维链，这是关键的结构属性。 尽管照明区域是二维的，但它们的中心只有一个自由度，因此重叠图案比任意圆的重叠图案要简单得多。 

测试用例最多可以有 (10^5) 个，而 (N)、(R) 和 (L) 分别可以有 (10^9) 个。 对于每个测试用例迭代 (N) 个灯的算法在最坏的情况下可能需要 (10^{14}) 次操作，这远远超出了时间限制。 每个测试用例我们需要恒定的算术量。 (R) 和 (L) 的较大值还意味着应该使用浮点运算仔细计算中间几何表达式，尽管 Python 的整数本身不会溢出。 

有几种边界情况很容易处理不当。 如果没有灯，例如（N=0，R=10，L=3），则无论其他参数如何，照明面积恰好为（0）。 以 (N\pi R^2) 开头的公式可以自然地处理此问题，但假设至少一个圆的代码可能会失败。 

如果(N=1)，例如(N=1，R=2，L=100)，则只有一个圆，所以答案是(4\pi)。 连续灯之间的距离无关紧要，因为不存在连续的灯对。 

如果 (L\ge 2R)，相邻圆不重叠。 例如，(N=2,R=1,L=2) 给出的面积为 (2\pi)。 使用重叠公式而不仔细处理边界可能会因浮点运算而引入微小的负平方根参数，或者错误地计算零区域交集。 

在另一个极端，(L=0) 意味着每个灯都处于完全相同的位置。 例如，(N=5,R=3,L=0) 的面积为 (9\pi)，而不是 (45\pi)。 正确的重叠公式必须认识到两个重合圆的交点是整个圆。 

最后，(R=0)使每个照明区域成为面积为零的点。 例如，(N=10,R=0,L=7) 的答案为 (0)。 应在计算 (L/(2R)) 等表达式之前处理这种情况，因为否则会发生被零除的情况。 

## 方法

 直接方法将从左到右处理灯，并明确维护新圆圈的哪些部分已经被照亮。 从几何角度来说，这可以通过计算与先前放置的圆的交点来完成。 该方法是正确的，因为可以通过将每个新圆之前未被覆盖的部分相加来获得并集区域。 

问题是可能有 (N) 个圆，并且简单的实现可能会将每个新圆与所有较早的圆进行比较。 然后，一个测试用例可能需要 (\Theta(N^2)) 配对检查，即 (N=10^9) 时的 (10^{18}) 次操作，尽管输入本身限制了测试用例的数量，而不是使这样的迭代变得实用。 当 (10^5) 个案例包含大 (N) 时，即使每个案例使用 (O(N)) 算法也太昂贵。 

有用的观察是，我们实际上不需要将一个圆与所有早期的圆进行比较。 考虑位置 (0,L,2L) 处的三个连续中心。 取既属于第一圆又属于第三圆的点。 由于中间圆心更接近两个外部圆心之间的每个点，因此该点也属于中间圆。 更一般地，当从左到右添加圆时，新圆中已被任何较早的圆覆盖的每个点也被紧邻的前一个圆覆盖。

因此，新圆与整个前一个并集的重叠区域与它与前一个圆的重叠区域完全相同。 即使多个圆圈同时重叠也是如此。 三重和高阶重叠不需要单独的包含-排除项，因为在添加每个新圆时它们已经被考虑在内。 

所以联合区的形式非常简单。 从 (N) 个单独的圆形区域 (N\pi R^2) 开始，并减去相同的相邻对重叠 (N-1) 次。 当(L\ge 2R)时，没有重叠，不需要减去任何东西。 

对于两个半径为 (R) 且圆心相距 (L) 的相等圆，它们 (0\le L<2R) 的交点面积为

 ## 2R^2\arccos\left(\frac{L}{2R}\right)

 \frac{L}{2}\sqrt{4R^2-L^2}。 
]

 因此，对于 (N>0)，

 [
 S=
 N\pi R^2-(N-1)S_{\text{重叠}},
 ]

 当 (L\ge 2R) 时 (S_{\text{overlap}}=0)。 

重要的部分不仅仅是认识标准的圆交线公式。 真正的简化是证明每个新圆仅在与其前一个圆共享的同一区域中与整个先前的联合相交。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个测试用例 (O(N^2)) | (O(N)) | 太慢了|
 | 最佳| 每个测试用例 (O(1)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 阅读（N）、（R）和（L）。 如果(N=0)或(R=0)，则输出(0)，因为不存在正面积照明区域。 
2. 计算一个圆的面积为 (\pi R^2)，然后将总面积初始化为 (N\pi R^2)。 这表示删除重叠之前的区域。 
3. 检查是否（L<2R）。 如果不是，则连续的圆是不相交或相切的，因此重叠面积为零，并且初始总和已经是答案。 
4. 当(L<2R)时，计算两个相邻圆的交集面积：

 \frac{L}{2}\sqrt{4R^2-L^2}。 
]

 第一项由两个扇形组成，而平方根项则删除弦和中心之间的两个三角形部分。 

1. 精确减去该重叠 (N-1) 次。 有 (N-1) 个相邻对，添加一个新圆会增加并集的整个面积减去与前一个圆的重叠部分。 
2. 用足够的位数打印结果浮点值，例如使用`:.10f`。 小数点后十位的精度远高于所需的精度 (10^{-6})。 

为什么它有效：当添加第 (i) 个圆时，假设其中的一个点也属于较早的圆。 前一个圆的中心位于新圆的中心和之前的圆的中心之间。 对于两个端点圆内的任意点，其到中间圆心的距离不大于其到较远端点圆心的距离。 因此该点也属于前一个圆。 因此，新圆与整个现有并集的交点正是它与前一个圆的交点。 每进行 (N-1) 次添加，相同的重叠区域就会被减去一次，因此多个圆圈覆盖的每个点在最终的并集中只被计算一次。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n, r, l = map(int, input().split())

        if n == 0 or r == 0:
            out.append("0.0000000000")
            continue

        circle_area = math.pi * r * r
        area = n * circle_area

        if l < 2 * r:
            x = l / (2.0 * r)

            # Protect acos from a possible tiny floating-point drift.
            x = max(-1.0, min(1.0, x))

            overlap = (
                2.0 * r * r * math.acos(x)
                - 0.5 * l * math.sqrt(4.0 * r * r - l * l)
            )

            area -= (n - 1) * overlap

        out.append(f"{area:.10f}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```第一个分支处理任何除法或平方根之前的两个零面积情况。 这是必要的，因为重叠公式包含 (L/(2R))。 

最初的`area`是所有 (N) 个圆的面积之和。 当 (L\ge2R) 时，圆不相交或相切，因此重叠为零，并且值已经正确。 

对于重叠的圆，`x`是 (L/(2R))，公共弦所对角的一半的余弦。 这`max`和`min`夹子保护`math.acos`来自浮点值，例如`1.0000000000000002`，尽管数学值恰好在有效区间内。 

下的表达式为`sqrt`每当 (L<2R) 时都是非负的。 比较是使用原始整数完成的，因此边界处不存在歧义（L=2R）。 

Python 整数可以表示涉及高达 (10^9) 值的乘积而不会溢出。 最终的几何计算使用`float`，其精度足以满足所需的 (10^{-6}) 容差。 在小数点后打印十位数字可以进一步防止格式错误。 

## 工作示例

 提供的示例代表一个具有 (N=4)、(R=1) 和 (L=1) 的测试用例。 语句中显示的输入已丢失换行符，因此它对应于：```
1
4 1 1
```对于这种情况，相邻圆重叠，因为 (1<2)。 

| 步骤| (N)| （右）| (左)| 初始面积| 对重叠 | 最终区 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 输入 | 4 | 1 | 1 | (4\pi) | (1.2283697\ldots) | (8.8812621\ldots) |

 中心相距 1 个单位的两个单位圆的重叠为

 \frac{2\pi}{3}-\frac{\sqrt3}{2}。

 有 3 个相邻对，因此并集面积为

 # 3\left(\frac{2\pi}{3}-\frac{\sqrt3}{2}\right)

 2\pi+\frac{3\sqrt3}{2}
 \约8.881262。 
]

 这说明了为什么即使四个圆可以参与多个圆重叠的区域，简单地减去成对重叠仍然是正确的。 每个圆仅添加一次，其新覆盖的区域完全由前一个圆决定。 

对于第二个示例，考虑两个相切圆：```
1
2 3 6
```这里 (2R=6=L)，所以圆恰好在一点相交。 点的面积为零，这意味着没有面积可以减去。 

| 步骤| (N)| （右）| (左)| 状况 | 重叠| 最终区 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 输入 | 2 | 3 | 6 | (L\ge2R) | 0 | (18\pi) |

 答案是（18\pi\approx56.5486677646）。 该迹线练习了精确的相切边界，并显示了为什么重叠分支必须使用`L < 2 * R`， 不是`L <= 2 * R`。

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def check(inp: str, expected: list[float], eps: float = 1e-6):
    actual = list(map(float, run(inp).split()))
    assert len(actual) == len(expected)

    for a, e in zip(actual, expected):
        assert abs(a - e) <= eps * max(1.0, abs(e)), (a, e)

## 边缘情况

 对于 (N=0)，考虑```
1
0 1000000000 1000000000
```算法立即进入第一个条件并返回`0.0000000000`。 不存在圆圈，因此不存在照明区域。 如果不检查灯的数量而使用半径，假设 (N\ge1) 的粗心实现仍可能返回非零表达式。 

对于 (N=1)，考虑```
1
1 2 100
```该算法计算一个圆面积 (4\pi)，并且永远不需要重叠公式，因为 (N-1=0)。 在这种情况下，间距值并不描述任何实际的灯对。 输出约为`12.5663706144`。 

对于重合圆，请考虑```
1
5 3 0
```重叠公式给出

 [
 2\cdot9\arccos(0)-0=9\pi。 
]

 初始总和为 (5\cdot9\pi)，并删除 (9\pi) 的四个重叠部分：

 [
 45\pi-4(9\pi)=9\pi。 
]

 因此，该算法正确地将所有五个灯视为一个发光圆盘。 这种情况也证实了该方法可以处理最大可能重叠的极端情况，而不需要超出一般交集表达式的特殊公式。 

对于切圆，考虑```
1
2 3 6
```由于(L=2R)，重叠分支被跳过。 答案是

 [
 2\pi\cdot3^2=18\pi。 
]

 这些圆仅共享一个边界点，其面积为零。 使用严格的`<`比较避免了不必要地计算零的平方根，并使边界的几何意义明确。 

对于分离的圆，请考虑```
1
4 2 5
```这里 (2R=4<L=5)，因此每个圆都与下一个圆不相交，因此也与所有其他圆不相交。 答案很简单

 [
 4\cdot\pi\cdot2^2=16\pi。 
]

 该算法从不调用`acos`或者`sqrt`在此分支中，因此不存在在其几何域之外评估交集公式的风险。 

对于许多严重重叠的圆，请考虑 (N=10,R=10,L=1)。 每个新添加的圆都与之前的并集重叠，但需要删除的量仍然恰好是两个圆重叠的部分。 该算法执行九次减法，而不是尝试枚举三重、四重或更高阶的交集。 这是解决方案的中心不变量，也是每个测试用例将整个几何问题减少到 (O(1)) 工作量的原因。
