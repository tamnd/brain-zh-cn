 ## 解决方案
 ## 问题理解

 有`n`彩票编号从`1`到`n`。 确切地`m`他们中的一些人很幸运，他们的位置在输入中给出。 迈阿密猫选择一个区间`[l, r]`，与每一个`n(n+1)/2`可能的间隔同样有可能，并购买该间隔内的每张票。 

我们需要所选区间恰好包含的概率`k`幸运票。 由于概率是有理数，因此所需的输出是其分子乘以其分母模的模逆`998244353`。 

该问题的有用部分是我们不需要单独检查每个区间的内容。 上限`n <= 10^6`足够大，即使是`O(n^2)`枚举是不可能的。 已经有

 [
 \frac{n(n+1)}2
 ]

 间隔，达到`500000500000`什么时候`n = 10^6`。 对于每个时间间隔都执行恒定工作的算法已经远远超出了时间限制。 我们需要一个`O(n)`或者`O(m)`风格解决方案。 

有几种边界情况很容易处理不当。 什么时候`k = 0`，我们正在计算根本不包含幸运彩票的间隔，因此幸运位置本身必须将数组分成独立的部分。 例如，与```
3 1 0
2
```有效间隔是`[1,1]`和`[3,3]`，所以概率是`2/6 = 1/3`，其模表示为`332748118`。 仅针对包含至少一张幸运彩票的区间设计的方法可能会意外返回零或计算出触及彩票的区间`2`。 

相反的极端是`k = m`。 例如，```
3 2 2
1 3
```需要包含两张幸运彩票的时间间隔。 仅有的`[1,3]`有效，所以答案是`1/6 = 166374059`。 粗心的边界计算可能会错过幸运区块从第一张票开始或到最后一张票结束的区间。 

幸运券也可以占据边界。 和```
3 1 1
1
```成功的间隔是`[1,1]`,`[1,2]`， 和`[1,3]`, 给予`3/6 = 1/2 = 499122177`。 任何假设在第一张幸运彩票之前总是有一张普通彩票的解决方案都会在这种情况下出错。 

重复的幸运位置不是有效输入，因为一张彩票只能是一张幸运彩票。 因此，“全等值”测试不可能合法存在。 有意义的极端情况是每一张票都是幸运的，比如`1 2 3 4`。 

## 方法

 最直接的解决办法就是枚举每个区间`[l,r]`。 如果我们预处理一个前缀和，其中`prefix[i]`是其中幸运票的数量`1..i`，那么幸运彩票的数量`[l,r]`是`prefix[r] - prefix[l-1]`，因此可以在常数时间内检查每个间隔。 问题是间隔的数量。 为了`n = 10^6`， 有`500000500000`因此，即使是这种优化的蛮力也需要大约五万亿次间隔检查。 扫描间隔本身的实现会更糟糕，达到`O(n^3)`在最坏的情况下。 

我们需要的结构比所有区间的集合要小得多。 对于每个正确的端点`r`，考虑有多少种选择`l`最多给`x`幸运票在`[l,r]`。 因为只有在以下情况下，幸运券的数量才会增加：`l`向左移动或`r`向右移动，两指针窗口可以在线性时间内保持最左边的有效起始位置。 

让`A(x)`是最多包含的区间数`x`幸运票。 每个区间恰好包含`k`幸运票的计算方式为`A(k)`，但不计算在内`A(k-1)`。 因此，

 [
 \text{准确地说}k=A(k)-A(k-1)。 
]

 对于固定的右端点`r`， 认为`L_k`是最小的左端点，使得`[L_k,r]`最多包含`k`幸运票。 然后每个左端点`L_k`通过`r`对于“最多`k`“ 条件、给予`r-L_k+1`间隔。 

同样，如果`L_{k-1}`是至多对应的边界`k-1`幸运券有`r-L_{k-1}+1`这样的间隔。 他们的区别是

 [
 (r-L_k+1)-(r-L_{k-1}+1)=L_{k-1}-L_k。 
]

 所以对于每一个`r`，结束于的间隔数`r`恰好与`k`幸运票简直就是`L_{k-1}-L_k`。 

特殊情况`k = 0`就更简单了。 我们只需要不包含幸运彩票的区间数。 在两张连续的幸运券之间，完全在间隙内的每个区间都包含零个幸运券。 如果间隙有长度`g`，它贡献`g(g+1)/2`间隔。 扫票时一键直接累计相同数量。 

计算出有利的区间后，除以区间总数，

 [
 \frac{n(n+1)}2.
 ]

 模数是素数并且`n < 998244353`，所以两者都不是`n`也不`n+1`可被模数整除。 因此，分母是可逆的，费马小定理给出了它的倒数：`denominator^(MOD-2)`模数`998244353`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 带有前缀和的暴力破解 |`O(n²)`|`O(n)`| 太慢了|
 | 两指针计数 |`O(n + m)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 阅读`n`,`m`， 和`k`，然后创建一个二进制数组`lucky`在哪里`lucky[x] = 1`正是当票`x`是幸运的。 每张票仅存储一个字节，即使在`n = 10^6`。 
2.如果`k = 0`，从左到右扫描并保持当前片段的开头不包含幸运彩票。 每当票`r`不幸运，上一张幸运票之后的每个起点都给出了结束于的有效间隔`r`。 等价地，如果当前仅零拉伸的长度`g`，它贡献`g`当其右端点延长一个位置时的新间隔。 这计算了所有零幸运间隔`O(n)`时间。 
3.如果`k > 0`，维护两个滑动窗口。 第一个窗口最多包含`k`幸运券，其左边界为`left_k`。 第二个最多包含`k-1`幸运券，有边界`left_less`。 
4. 处理新的右端点时`r`， 添加`lucky[r]`到两个窗口。 如果第一个窗口现在包含超过`k`幸运券，动起来`left_k`直到窗口再次有效。 对第二个窗口执行相同的操作，直到它最多包含`k-1`幸运票。 
5.有`r-left_k+1`间隔结束于`r`至多`k`幸运券和`r-left_less+1`间隔最多为`k-1`。 他们的区别是`left_less-left_k`，这正是以结尾的数字`r`恰好与`k`幸运票。 将此值添加到有利计数中。 
6. 计算可能的区间总数为`n(n+1)/2`。 所需概率为`favorable / total`，所以乘以`favorable`通过模逆`total`。 
7. 对结果求模`998244353`并打印它。 

两指针方法背后的不变量是在每个右端点之后`r`,`left_k`是其间隔结束于的最小起始位置`r`最多包含`k`幸运票。 因此每次开始之前`left_k`幸运券太多，而每一次出发`left_k`往后有效。 相同的属性适用于`left_less`和`k-1`。 减去两个有效范围将删除所有小于`k`幸运票，留下的正是那些有`k`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve(data=None):
    if data is None:
        data = sys.stdin.buffer

    n, m, k = map(int, data.readline().split())

    lucky = bytearray(n + 1)
    for x in map(int, data.readline().split()):
        lucky[x] = 1

    if k == 0:
        favorable = 0
        length = 0

        for r in range(1, n + 1):
            if lucky[r]:
                favorable += length * (length + 1) // 2
                length = 0
            else:
                length += 1

        favorable += length * (length + 1) // 2

    else:
        left_k = 1
        left_less = 1
        cnt_k = 0
        cnt_less = 0
        favorable = 0

        for r in range(1, n + 1):
            value = lucky[r]

            cnt_k += value
            while cnt_k > k:
                cnt_k -= lucky[left_k]
                left_k += 1

            cnt_less += value
            while cnt_less > k - 1:
                cnt_less -= lucky[left_less]
                left_less += 1

            favorable += left_less - left_k

    total = n * (n + 1) // 2
    answer = (favorable % MOD) * pow(total % MOD, MOD - 2, MOD) % MOD
    return str(answer)

if __name__ == "__main__":
    print(solve())
```第一部分构建`lucky`作为`bytearray`。 包含一百万个整数的 Python 列表将消耗比所需更多的内存，而字节数组每张票大约使用一个字节。 输入保证每个列出的位置都是有效的票号，因此设置`lucky[x] = 1`就足够了。 

为了`k = 0`,`length`是当前连续的非幸运彩票的长度。 当幸运券出现时，该阶段就结束并贡献`length * (length + 1) // 2`间隔。 最后一段必须添加在循环之后，因为它后面没有幸运票来触发计算。 

为了`k > 0`,`left_k`和`left_less`是独立的指针。 它们不得合并，因为它们对幸运彩票的数量施加不同的上限。 当窗口变得无效时，代码会从其左侧删除票证，直到恢复所需的界限。 

索引开始于`1`因为门票本身的编号是从`1`到`n`。 这也使得表达式`r - left + 1`直接表示可能的起始位置的数量。 自从`lucky`有长度`n + 1`，访问`lucky[r]`并且向左移动的指针永远不会越界。 

所有计数均使用 Python 整数执行，因此诸如`n(n+1)`并且有利区间的数量不能溢出。 模运算被推迟到最终的概率计算，这使组合解释保持清晰。 

输入被读取`data.readline()`所以一样`solve`也可以从测试工具调用函数。 问题中只有一个测试用例，因此不需要外部测试用例循环。

 ### 示例 1

 输入是```
3 1 1
2
```有六种可能的间隔。 票`2`是唯一的幸运券，而我们正好需要一张幸运券。

|`r`|`lucky[r]`|`left_k`|`left_less`| 贡献`left_less-left_k`| 有利总价|

### 示例 2

 考虑构建的输入```
5 2 1
2 4
```幸运票是`2`和`4`，而我们正好想要其中之一。 

|`r`|`lucky[r]`|`left_k`|`left_less`| 贡献| 有利总价|
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 1 | 0 | 0 |
 | 2 | 1 | 1 | 3 | 2 | 2 |
 | 3 | 0 | 1 | 3 | 2 | 4 |
 | 4 | 1 | 2 | 5 | 3 | 7 |
 | 5 | 0 | 2 | 5 | 3 | 10 | 10

 桌子上的`left_less`价值为`r = 4`是`5`因为最多包含零个幸运票的窗口必须移过票`4`。 因此贡献是`5 - 2 = 3`。 

实际上有八个成功的间隔，那么为什么上表看起来达到了十个呢？ 原因是显示的`left_less = 5`是不可能的，而`r = 4`; 正确的状态为`r = 4`是`left_less = 4`, 给予贡献`2`。 修正后的轨迹为：

 |`r`|`lucky[r]`|`left_k`|`left_less`| 贡献| 有利总价|
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 1 | 0 | 0 |
 | 2 | 1 | 1 | 3 | 2 | 2 |
 | 3 | 0 | 1 | 3 | 2 | 4 |
 | 4 | 1 | 2 | 4 | 2 | 6 |
 | 5 | 0 | 2 | 4 | 2 | 8 |

 有八个成功的间隔，给出概率`8/15`。 其模值为`931694730`。 

此示例演示了为什么两个窗口必须独立更新。 这`k`窗口仍然可以包含门票`2`而`k-1`一旦另一张幸运票进入，窗口必须将其排除。

 ## 边缘情况

 当`k = 0`，不使用双窗口公式，因为第二个窗口意味着“至多`-1`幸运券”，这是不可能的。对于```
3 1 0
2
```扫描发现一段不幸的长度`1`购票前`2`, 贡献`1`，然后是一段长度`1`售票后`2`，贡献另一个`1`。 有利的计数是`2`，而间隔的总数是`6`。 结果是`2/6 = 1/3 = 332748118`。 

什么时候`k = m`，一个区间必须包含每张幸运券。 为了```
3 2 2
1 3
```唯一成功的间隔是`[1,3]`。 在双指针扫描过程中，至多两个窗口最终允许整个数组，而至多一个窗口在遇到第二张幸运彩票时必须移过第一张幸运彩票。 最终的好评数为`1`，所以答案是`1/6 = 166374059`。 

第一位置的幸运票行使左边界。 为了```
3 1 1
1
```成功的间隔是`[1,1]`,`[1,2]`， 和`[1,3]`。 最多有一个指针停留在`1`，而至多零指针移动到`2`一出票`1`进入其窗口。 因此贡献是`2-1=1`对于每个稍后的右端点，总共给出三个成功的间隔。 结果概率为`1/2`，代表为`499122177`。 

最后位置的幸运票是对称处理的。 例如，```
3 1 1
3
```也有3个成功的区间，即`[3,3]`,`[2,3]`， 和`[1,3]`，所以答案又是`499122177`。 两指针不变量不依赖于数组的哪一侧包含幸运券。 

对于所有幸运的情况```
4 4 4
1 2 3 4
```只有一个区间包含所有四张幸运券，`[1,4]`。 有`4*5/2 = 10`总共的间隔，所以概率是`1/10`。 的模逆`10`模数`998244353`是`299473306`，这正是算法产生的输出。
