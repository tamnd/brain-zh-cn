 ## 解决方案
 ## 问题理解

 我们有编号从 1 到 n 的礼物。 孩子可以选择其中的任何子集，但有一个限制：每当孩子接受礼物 x 时，他们就不能同时接受礼物 2x。 所选套装的价值是所有所选礼物编号的总和，我们需要最大可能的价值。 

输入仅包含 n，其中 1≤n≤10 5。输出是有效子集的最大和。 

上限 10 5 排除了枚举所有子集。 有 2 n 个可能的子集，因此即使在恒定时间内检查每个子集也已经是无望的了。 对于仅连接一个与该数字两倍的数字的限制的问题，也不需要围绕 O(n 2 ) 的解决方案。 O(n) 或 O(nlogn) 解决方案是自然目标。 

有几个小案例暴露了常见的错误。 用于输入`1`，唯一可能的选择是礼物1，所以答案是`1`。 假设每个数字都有前一个数字或尝试从 2 开始的解决方案可能会意外返回零。 

用于输入`2`，这两个礼物是冲突的，因为 1 和 2=2⋅1 不能同时被选择。 最好的选择只是`2`，所以答案是`2`。 一个粗心的解决方案，简单地将除某些固定边界之外的所有数字相加，可能会产生`3`。 

用于输入`5`，最优集合是 {1,3,4,5}，给出`13`。 特别是，选择两者都是正确的`4`和`1`，因为禁止关系具体是在 x 和 2x 之间，而不是在任意偶数和奇数之间。 将具有相同奇偶校验的所有数字视为冲突的实现将错误地拒绝该集合。 

## 方法

 直接暴力解决方案考虑 {1,2,…,n} 的每个子集，检查它是否同时包含某个 x 的 x 和 2x，并保留最大的有效总和。 正好有 2 n 个子集。 如果通过扫描所有 n 个数字来检查有效性，最坏情况的工作是 n2 n 个检查。 即使忽略额外的因子 n，2 100000 也远远超出了任何可执行的范围。 

蛮力之所以有效，是因为每一个可能的选择都被明确地检查，但它完全忽略了冲突关系的特殊结构。 唯一禁止的配对是

 (1,2),(2,4),(3,6),(4,8),…

 更一般地，每个数字都属于通过重复乘以 2 获得的链。例如，奇数部分 3 的数字形成

 3、6、12、24……

 并且只有该链的相邻元素发生冲突。 

在这样的一条链中，值严格增加，并且每个值恰好是其前一个值的两倍。 这使得贪婪的选择成为可能。 从大到小考虑数字。 当我们到达 x 时，唯一可以与之冲突的较大数字是 2x。 如果已经选择了 2x，则必须拒绝 x。 如果没有选择2x，我们应该选择x。 

为什么第二种情况总是安全的？ 当 x 为偶数时，唯一与 x 冲突的较小数字是 x/2。 如果最优解使用 x/2 而不是 x，则用 x 替换 x/2 会增加总和。 x/2以下可能的附加选择形成另一个几何递减序列，其总和仍然小于x。 同样，沿着一条链，选择较大的可用元素优先于选择其前任元素。 

这意味着我们可以按降序处理所有数字。 在我们检查x的那一刻，2x已经确定了。 如果选择2x，则无法选择x。 否则，选择 x 是最佳的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n2 n ) | O(n) | 太慢了|
 | 降序贪婪| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 创建数组`chosen`， 在哪里`chosen[x]`记录礼物x是否已被选择。 我们处理从 n 到 1 的数字，因此当我们检查 x 时，2x 的状态是已知的。 
2.从回答开始`0`。 对于从n到1的每个x，检查2x是否存在并且已被选择。 如果选择 2x，则跳过 x，因为选择两者都会违反条件。 
3. 如果 2x 不存在或尚未选择，则选择 x 并将 x 添加到答案中。 这是贪婪的选择，因为每个大于 x 的冲突数都已被考虑，而 x 严格地比其唯一可能的较小冲突邻居 x/2 更有价值。 
4. 处理完所有数字后，输出累加和。 每个选定的数字对都是有效的，因为当选择其双倍时，数字就会被拒绝。 

### 为什么它有效

 关键的不变量是，在处理每个大于 x 的数字后，每个加倍链内所做的选择对于该处理后缀来说是最佳的。 当达到 x 时，唯一可能与之冲突的较大数字是 2x。 如果选择 2x，则强制拒绝 x。 如果未选择 2x，则选择 x 至少与选择任何较小的冲突值一样好，因为值沿链减少了两倍。 因此，贪心决策保留了剩余后缀的最优解。 从 n 到 1 重复应用这个参数可以为每个链提供一个最优解，并且这些链是独立的，因此它们的最优选择一起形成一个全局最优集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    chosen = bytearray(n + 1)
    ans = 0

    for x in range(n, 0, -1):
        if 2 * x <= n and chosen[2 * x]:
            continue

        chosen[x] = 1
        ans += x

    print(ans)

if __name__ == "__main__":
    solve()
```这`chosen`数组只存储零或一，所以`bytearray`足够了并且内存使用量非常小。 迭代时`x`, 索引`2 * x`仅当`2 * x <= n`。 对于较大的`x`，不存在冲突的较大礼物，所以礼物总是可以选择的。 

降序是核心实现细节。 如果我们从小到大处理数字，那么 2x 的状态还不知道，贪婪决策也不能直接得到。 

该语句允许 n 达到 10 5，但答案可以是 n 2 的数量级，因此在具有固定宽度整数的语言中，使用正常的数学整数类型是必要的。 Python 整数自动增长，因此不需要特殊的溢出处理。

## 测试用例

 原始声明提供了一个具体示例，`n = 5`，有答案`13`。 由于输入仅由 n 组成，因此没有要测试的重复或“全相等”输入值。 最接近的等效方法是测试几个连续的值并确保每个双链都是独立处理的。```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())

    chosen = bytearray(n + 1)
    ans = 0

    for x in range(n, 0, -1):
        if 2 * x <= n and chosen[2 * x]:
            continue
        chosen[x] = 1
        ans += x

    print(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# provided sample
assert run("5\n") == "13", "sample 1"

# minimum size
assert run("1\n") == "1", "minimum n"

# smallest conflicting pair
assert run("2\n") == "2", "1 and 2 cannot both be selected"

# several doubling chains
assert run("6\n") == "16", "chains 1-2-4 and 3-6"

# boundary around a power of two
assert run("8\n") == "27", "power-of-two boundary"

# maximum-size input, checked independently by the same greedy recurrence
def reference(n: int) -> int:
    chosen = bytearray(n + 1)
    ans = 0
    for x in range(n, 0, -1):
        if 2 * x <= n and chosen[2 * x]:
            continue
        chosen[x] = 1
        ans += x
    return ans

assert run("100000\n") == str(reference(100000)), "maximum n"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`1`|`1`| 最小尺寸边界|
 |`2`|`2`| 第一对禁忌 |
 |`6`|`16`| 多个独立双链 |
 |`8`|`27`| 2 次方边界 |
 |`100000`|`reference(100000)`| 最大约束和线性性能|

 ## 边缘情况

 对于 n=1，循环仅检查 x=1。 由于 2x=2>n，不存在冲突的更大礼物，所以`1`被选中，答案就变成了`1`。 因此输出是`1`。 

对于 n=2，算法首先选择`2`。 当它达到`1`,`chosen[2]`已经是真的了，所以`1`被跳过。 答案是`2`。 这直接处理了尽可能小的冲突。 

对于 n=5，算法选择`5`,`4`， 和`3`, 跳过`2`因为`4`被选中，然后选择`1`因为`2`没有被选中。 所得总和为 5+4+3+1=13。 这说明了为什么该决定`1`不能简单地取决于是否`1`是奇数还是偶数。 这取决于其双精度的实际选择。 

对于n=8，链1,2,4,8贡献8+2=10，而独立链3,6,5,7贡献6,5,7。总数是10+6+5+7=28，不是`27`。 这种情况对于捕获 2 的幂附近的差一错误特别有用。 正确的断言为`8`因此是：```
assert run("8\n") == "28", "power-of-two boundary"
```最大情况 n=100000 执行完整循环。 每次迭代仅执行数组查找、比较，可能还执行加法，因此总工作保持线性。 答案是使用 Python 的任意精度整数类型累加的，即使最佳总和远大于 2 31 −1，也可以避免溢出。
