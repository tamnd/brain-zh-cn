 ## 解决方案
 ## 问题理解

 我们在同一组顶点上获得了两个不同的结构，标记为从 1 到 N。一个结构是一棵树，因此在任何两个顶点之间都存在一条简单路径。 另一种结构是任意无向简单图。 

对于任何有序的顶点对 (u, v)，我们查看树中连接 u 到 v 的唯一路径。 然后我们询问这个精确的顶点序列是否也可以作为图中的有效路径来遍历。 如果是，则该对称为好对。 每个顶点本身都很好，因为从 u 到 u 的路径没有边。 

任务是计算有多少有序对是好的。 

约束条件将 N 和 M 设为 200,000。 这立即排除了任何单独检查对或模拟每个查询路径的解决方案。 任何接近 O(N^2) 甚至 O(NM) 的方法都会太慢。 我们应该期望接近线性或线性算数时间，可能是 O(N + M) 或 O((N + M) log N)。 

一个微妙的点是“G 中的路径”的含义。 它不需要唯一性，只需要存在。 所以如果树路径是u→a→b→v，我们只需要那些边（u，a），（a，b），（b，v）存在于G中； G 中的额外边并不重要，只要它们不使该序列的存在无效即可。 

一个常见的错误是认为我们必须匹配 G 中的最短路径或确保不存在替代路由。 那不是必需的。 

一个值得澄清的边缘情况是 G 与树相同。 那么每一对都是好的，所以答案是 N²。 另一个极端是当G与树边没有重叠时； 那么只有 (u, u) 对有效，给出 N。 

## 方法

 蛮力思想是从定义开始的。 对于每个有序对 (u, v)，我们计算树中的唯一路径，然后检查该路径上的每条边是否存在于 G 中。如果路径长度为 k，则每对需要 O(k)。 对所有对求和，在最坏的情况下这将变为 O(N^2)，因为对于链形树中的大多数对来说，树路径可能很长。 即使我们使用散列加速边缘存在性检查，对本身的数量仍然是二次的，这远远超出了限制。 

关键的观察是我们实际上从来不需要独立地推理任意对。 当一对 (u, v) 之间的树路径上的每一条边都存在于 G 中时，这对 (u, v) 就是好的。这将问题从对上的路径检查问题转换为树上的边缘过滤问题。 

我们可以将每个树边分类为“可用”或“损坏”，具体取决于它是否也出现在 G 中。如果我们在树中只保留可用的边，我们就得到了一个森林。 在这个森林中，任何两个顶点都是连接的，当且仅当它们的原始树路径仅使用可用的边。 这个条件就相当于夫妻关系很好。 

因此，问题简化为在该过滤树中查找连接的组件并对每个组件内的有序对的数量求和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N^2) | O(N^2) | O(N) | 太慢了 |
 | 过滤树边+组件| O(N + M) | O(N + M) | 已接受 |

 ## 算法演练

 我们为 G 的边构建快速隶属结构，然后相应地过滤树。

1. 将 G 的所有边存储在以有序对 (min(x, y), max(x, y)) 为键的哈希集或字典中。 这允许恒定时间检查 G 中是否存在树边。 
2. 为所有 N 个顶点初始化一个不相交集并集 (DSU) 结构，其中最初每个顶点都是其自己的组件。 该 DSU 将仅使用“好”树边来表示连接。 
3. 对于树中的每条边 (a, b)，使用哈希集检查它是否存在于 G 中。 如果是，则在 DSU 中合并 a 和 b。 如果没有，我们就完全忽略它，将其视为损坏。 
4.处理完所有树边后，每个DSU分量精确对应于由可用边形成的连通分量。 
5. 对于每个 DSU 组件，计算其大小 s。 组件内的每个有序对 (u, v) 都是好的，包括 (u, u)，因此它贡献 s × s。 
6. 对所有分量求和 s × s 并输出结果。 

唯一的微妙之处是我们没有明确地构建新图。 DSU 直接模拟过滤树中的连通性，无需邻接表。 

### 为什么它有效

 该树保证任意两个顶点之间都有唯一的简单路径。 该路径完全由树边的顺序决定。 当唯一路径上的每条边都存在于 G 中时，一对 (u, v) 就是好的。这相当于说路径上的每条边都被标记为可用。 

如果路径上的所有边都可用，则 DSU 连接性可确保 u 和 v 最终位于同一组件中，因为我们精确合并了这些边。 相反，如果它们位于同一 DSU 组件中，则存在完全由可用边组成的路径，该路径必须与唯一的树路径一致，因为树没有替代路由。 这种一一对应保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]

def main():
    n, m = map(int, input().split())

    tree_edges = []
    for _ in range(n - 1):
        a, b = map(int, input().split())
        tree_edges.append((a, b))

    g_edges = set()
    for _ in range(m):
        x, y = map(int, input().split())
        if x > y:
            x, y = y, x
        g_edges.add((x, y))

    dsu = DSU(n)

    for a, b in tree_edges:
        x, y = (a, b) if a < b else (b, a)
        if (x, y) in g_edges:
            dsu.union(a, b)

    comp_size = {}
    for i in range(1, n + 1):
        root = dsu.find(i)
        comp_size[root] = comp_size.get(root, 0) + 1

    ans = 0
    for s in comp_size.values():
        ans += s * s

    print(ans)

if __name__ == "__main__":
    main()
```该代码首先将 G 的所有边存储在一个具有标准化排序的集合中，以便边查找的时间恒定。 然后，它迭代树的边，并且仅当该边存在于 G 中时才合并端点。在 DSU 构造之后，它通过将所有顶点压缩到其根并累积计数来计算组件大小。 

一个常见的实现陷阱是忘记对树和图之间的边进行一致的标准化。 另一个是在没有最终路径压缩的情况下迭代 DSU 父级，这可能会错误计算组件大小。 最后的循环在每个节点上显式调用 find 以保证正确性。 

## 工作示例

 考虑线树中具有四个节点和 G 中的三个边的样本结构。树边是 (1,2)、(2,3)、(3,4)。 图边允许除 (1,2) 之外的所有边。 

过滤后，只有边 (2,3) 和 (3,4) 仍然可用。 DSU 组件变为 {1}、{2,3,4}。 贡献为 1² + 3² = 1 + 9 = 10。 

现在考虑第二个示例，其中树是以 1 为中心的星形，边为 (1,2)、(1,3)、(1,4)，并且 G 仅包含 (1,2) 和 (1,3)。 

过滤后，1、2、3 形成一个组分，而 4 被分离。 

下表跟踪 DSU 工会。 

| 边缘处理 | 在 G | DSU 状态 |
 | ---| ---| ---|
 | (1,2) | 是的 | {1,2}、{3}、{4} |
 | (1,3) | 是的 | {1,2,3}, {4} |
 | (1,4) | 没有| 不变|

 最终尺寸为 3 和 1，即 3² + 1² = 10。 

这些示例表明，只有保留的树边缘才重要，并且所有推理都简化为该过滤结构中的连接性。

 ## 边缘情况

 一种边缘情况是 G 中不存在树边。在这种情况下，每个顶点在 DSU 中保持孤立。 该算法产生 N 个大小为 1 的分量，每个分量贡献 1，因此答案为 N。这符合只有 (u, u) 对有效的事实。 

另一种情况是当 G 包含所有树边加上附加边时。 额外的边不会影响 DSU 并集，因为只处理树边。 整棵树成为一个组件，产生 N² 有序对，这是正确的，因为每条树路径都存在于 G 中。 

最后一个微妙的情况是 G 以不与树对齐的方式断开连接。 由于 DSU 完全忽略非树边，因此此类边不能错误地合并组件。 只有受 G 限制的树连通性才重要，这正是定义好对的条件。
