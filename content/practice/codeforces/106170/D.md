 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 每个测试用例都描述了音乐流派的集合，其中第 i 个流派包含 ci 种不同的歌曲。 我们必须从这个池中总共选择 m 首歌曲，并且只要我们不超过每个流派的可用歌曲，我们就可以选择任何子集。 

选择由整数 ki 表示，其中 ki 是我们从流派 i 中选择的歌曲数量。 这些值必须满足 0 ≤ ki ≤ ci 并且它们的总和必须恰好为 m。 在跨流派分配 m 个选择的所有有效方法中，我们希望分配尽可能平衡。 不平衡度量是所有类型中最常用的类型和最少使用的类型之间的差值，即 max ki 减去 min ki。 

一个关键的微妙之处在于，我们根本不使用的类型仍然贡献最低限度。 因此，某些 ki 等于 0 的配置会立即推动目标向上，除非每种类型至少使用一次。 这与我们必须尊重能力 ci 的约束强烈相互作用。 

这些约束意味着所有测试用例的流派总数很大，高达 2·10^5，并且 ci 可以大到 10^9。 这排除了尝试所有分布或执行按单位模拟分配的任何解决方案。 每个测试用例中的 n 甚至是二次方都不会通过。 

尝试将歌曲增量分配到当前最小的 ki 的天真贪婪也可能会巧妙地失败，因为早期的局部平衡可能会迫使稍后违反 ci，而最佳解决方案取决于全局均衡阈值。 

当 m 小于 n 时，就会出现常见的边缘情况。 例如，如果 n = 5，m = 2，并且所有 ci 都很大，那么我们能做的最好的事情就是将一首歌曲分配给两种流派，将零分配给其余流派，产生最小值 0 和最大值 1，因此答案为 1。总是试图在所有流派之间均匀分布的贪婪者可能会在检查可行性之前错误地尝试为每种流派分配 1。 

另一种极端情况是容量差异很大。 例如，如果一种流派的 ci = 100，而其他流派的 ci = 1，并且 m 很大，则限制流派会强制达到可达到的最大最低水平，这必须在全局范围内而不是按流派进行考虑。 

## 方法

 关键的困难在于，我们将 m 个相同的单元分配到 n 个有界的 bin 中，并且我们希望最小化最满和最少填充的 bin 之间的差异。 这表明最终的配置应该尽可能“平坦”，这意味着大多数 ki 应该聚集在一个小区间 [L, R] 周围，并且 R − L 最小化。 

蛮力方法会尝试将 m 首歌曲的所有可能分配到尊重容量的流派中。 即使我们只考虑计数而不考虑排列，这也相当于一个有界整数组合问题，其复杂性相当于将 m 分成 n 个部分的组合，并且呈指数增长。 即使 DP 超过 (i, 剩余 m, 当前最小值, 当前最大值) 也会太大，因为 m 可能很大并且 n 高达 2 · 10^5。 

关键的见解是扭转观点：我们不构造 ki，而是修复候选差异 D = max ki − min ki，并询问是否存在实现它的有效分配。 这将问题转化为对结构化范围约束的可行性检查。 

如果我们确定一个最低水平 L，那么每种类型都必须至少采用 L，除了那些由于容量限制而被迫低于 L 的类型。 一旦选择了 L，每个流派最多可以花费 min(ci, L + D)。 这将问题转变为检查我们是否可以在这些边界内分配至少 m 和最多 m 个单位，同时将所有 ki 保持在允许的区间内。

单调性是关键的结构：如果一定的差异 D 是可行的，那么任何更大的 D 也是可行的，因为放宽上限只会增加灵活性。 这允许对 D 进行二分搜索。对于每个 D，我们计算在从所选基线 L 导出的约束下可实现的最大和最小可能总和，并检查是否可以实现 m。 

由于 L 本身在最终配置中并未全局固定，因此我们观察到在最优解决方案中，最小 ki 将是由排序 ci 引起的 ci 限制或阈值限制值之一。 这导致了对容量进行排序并尝试在每个有意义的断点处锚定最小值的标准技巧。 

我们对 ci 进行排序并考虑候选最低级别 L。对于固定的 L，流派分为 ci < L 的流派，它必须采用所有 ci 并贡献固定的总和，以及 ci ≥ L 的流派，它可以在 L 和 ci 之间进行。 然后，我们测试实现 m 的可行性，并计算有界区间内的最佳可能最大值，从而得出最终的价差。

 ## 算法演练

 1. 对数组c进行非降序排序。 排序使我们能够以结构化方式推理候选最低级别 L，因为低于 L 的所有类型表现一致。 
2. 预先计算c的前缀和。 如果我们设置阈值 L，这可以让我们快速计算出有多少首歌曲是“强制”的，因为所有 ci < L 都必须被完全采用。 
3. 迭代每个可能的位置 i，将 ci 视为潜在的最小级别 L = ci。 这是有效的，因为在最佳解决方案中，最小分配值将与容量引起的某些边界对齐。 
4. 对于固定的 L，计算有多少流派低于 L。对于这些流派，它们的贡献固定为 ci，因为我们无法达到 L。这定义了一个基本总和。 
5. 对于 ci ≥ L 的流派，每个流派的贡献可以在 L 和 ci 之间。 我们计算总的闲置容量，并确定是否可以通过在 L 之上分配额外的单元来恰好达到 m 总计。 
6. 如果可行，通过贪婪地填充剩余的松弛来计算此 L 下最大流派的最大可能分配值，确保我们遵守 ci 边界。 
7. 跟踪所有候选 L 上 max ki − min ki 的最小可能值。 

### 为什么它有效

 在任何最佳分配中，ki 中最小的非零值或零值必须对应于一个阈值，在该阈值中，我们要么达到容量边界，要么达到统一的平衡点，在该点进一步提高最小值将使总数超过 m。 由于这两个约束都是线性且单调的，因此解决方案空间会崩溃以检查由排序的 ci 定义的断点。 一旦 L 固定，所有有效配置在总分配方面形成凸区间，因此可行性降低为将 m 与可计算范围进行比较。 这保证了候选L值中不会遗漏最优解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, m = map(int, input().split())
        c = list(map(int, input().split()))
        c.sort()
        
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + c[i]
        
        ans = float('inf')
        
        for i in range(n):
            L = c[i]
            
            # genres < i are below L, all fully taken
            base = pref[i]
            
            # remaining genres
            k = n - i
            
            # we try to distribute remaining m - base among k genres
            rem = m - base
            
            if rem < 0:
                continue
            
            # each of these k genres can take at least L, so subtract baseline L*k
            if rem < L * k:
                continue
            
            rem -= L * k
            
            # extra capacity above L
            cap = 0
            for j in range(i, n):
                cap += c[j] - L
            
            if rem > cap:
                continue
            
            # compute max ki among large side
            # worst-case spread: smallest is L, largest is L + distributed extras
            mx = L + min(c[n - 1] - L, rem)
            ans = min(ans, mx - L)
        
        out.append(str(ans if ans != float('inf') else 0))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案首先对容量进行排序，以便可以在有意义的边界上测试每个候选最低级别。 前缀和用于快速计算无法达到所选阈值 L 的流派的强制选择。对于每个 L，我们统一对待所有剩余流派，并检查是否可以分配剩余所需的歌曲，同时尊重下限（每个活动流派至少 L）和上限（每个流派 ci）。 如果分配可行，我们会计算该配置中最小 L 和最大可实现值之间还存在多少不平衡。 

一个微妙的实施细节是确保可行性检查尊重所需的最低分配和 L 以上的总容量。缺少任何一个条件都会导致接受不可能的分配或拒绝有效的分配。

这证实了算法正确地考虑了强制性基线和剩余分布。

 ## 边缘情况

 当 m 小于 n 时，会出现一种边缘情况，迫使许多 ki 为零。 例如，n=5，m=2，c都很大。 正确答案是 1，因为我们可以分配 1, 1, 0, 0, 0。任何假设必须使用所有类型的方法在这里都会失败。 该算法通过可行性检查来处理此问题，其中 rem 变为负值，除非有效地 L = 0，从而防止无效的统一假设。 

当一种类型的容量极大而其他类型的容量很小时，就会出现另一种边缘情况。 例如，c = [1, 1, 1, 100]，m = 5。最优值是 [1, 1, 1, 2]，给出差值 1。该算法通过仅允许最多 ci − L 的剩余分配来捕获这一点，从而防止大 bin 吸收所有剩余而不影响最小边界结构。
