 ## 解决方案
 ## 问题理解

 我们被要求计算第_n_个六边形数。 六边形数字代表图形数字模式，其中每个数字计算形成具有连续层的六边形的瓷砖总数。 第 n 个六边形数的公式由下式给出$H_n = 2n^2 - n$。 从概念上讲，第一个六边形数字是单个图块，第二个六边形数字添加周围层以形成更大的六边形，依此类推。 

输入是单个整数$n$表示要计算哪个六边形数，限制为 1 ≤ n ≤ 100。输出是单个整数，即相应六边形数的值。 

给定约束条件$n \le 100$，计算量仍然很小。 即使是最大的值，$H_{100} = 2 \cdot 100^2 - 100 = 19900$，很容易适合标准的 32 位或 64 位整数。 这意味着不需要对大整数进行特殊处理或优化来提高性能。 简单的方法已经很有效，但仔细推理公式可以确保正确性。 

潜在的边缘情况包括最小的输入$n = 1$应该输出 1，并确认公式正确缩放$n = 100$。 粗心的实现可能会误用公式，忘记减去$n$，或使用会引入舍入误差的浮点计算。 

## 方法

 蛮力方法会尝试通过将每层中的图块相加到迭代来构造六边形数$n$第-层。 例如，可以求和$1 + 6 + 12 + 18 + \dots$其中每项对应于每个新层添加的图块。 虽然正确，但这种方法是不必要的，因为公式$H_n = 2n^2 - n$直接给出答案。 迭代地添加层是多余的并且会增加复杂性，但对于$n \le 100$它仍然会立即执行。 

关键的观察结果是该问题提供了一个封闭式公式。 认识到这一点可以在恒定时间内进行直接计算。 除了计算之外，不依赖于先前的数字$n^2$并进行简单的算术运算。 问题简化为计算输入的二次表达式$n$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（迭代求和层）| O(n) | O(1) | O(1) | 已接受但没有必要 |
 | 公式（直接计算）| O(1) | O(1) | O(1) | O(1) | 已被接受且最佳 |

 ## 算法演练

 1.读取整数$n$来自输入。 这代表我们需要计算哪个六边形数。 
2. 计算$n^2$。 随着层数的增加，这捕获了六边形数的二次增长。 
3. 乘法$n^2$2. 六边形数字的模式将平方项加倍，以说明在六个方向上向外延伸的瓷砖。 
4. 减法$n$从结果来看。 这纠正了加倍步骤中中央图块的过度计数，与公式对齐$H_n = 2n^2 - n$。 
5. 打印结果。 这就是$n$-th 六边形数。 

为什么它有效：不变的是，该公式精确地计算了六边形排列中的瓷砖数量，最多可达$n$第-层。 每层都会添加可预测数量的图块，二次项捕获增长情况，而线性减法则对多次计数的单个中心图块进行校正。 由于我们直接应用该公式，因此任何迭代步骤都不会引入错误。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
hex_num = 2 * n * n - n
print(hex_num)
```该代码读取单个整数，使用封闭式公式计算六边形数，然后打印它。 先乘后减确保整数运算。 使用`sys.stdin.readline`保证快速输入，尽管这里由于单行而导致差异可以忽略不计。 乘法顺序可以防止运算符优先级错误。

 ## 边缘情况

 对于$n = 1$，算法计算$2*1^2 - 1 = 1$，这正是第一个六边形数。 为了$n = 100$，计算$2*100^2 - 100 = 19900$确认公式比例正确。 这两种情况都表明该算法可以处理极端边界，而不会出现相差一错误或整数溢出。 该算法一致地将公式应用于任何$n$在限制范围内。
