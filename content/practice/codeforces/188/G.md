 ## 解决方案
 ## 问题理解

 任务是以非降序对整数列表进行排序。 您将获得列表的大小、_n_，然后是 _n_ 个整数，每个整数在单独的行上，值范围从 1 到 100。输出应该是打印在一行上的相同整数，按升序排列，并用空格分隔。 允许重复值，数组可以小到单个元素，也可以大到 100 个元素。 

约束很小：n 最大为 100，每个数字都在 1 到 100 之间，该算法可以在不超过时间限制的情况下执行 O(n²) 操作。 这意味着即使是简单的排序算法（例如插入排序或选择排序）也足够快。 另一方面，如果需要，该问题鼓励使用更有效的方法，但并不严格需要复杂的优化。 边缘情况包括已经排序的数组、所有元素都相等的数组以及最大和最小数字出现多次的数组。 例如，对于输入```
5
3
3
3
3
3
```输出应该是```
3 3 3 3 3
```在这种情况下，尝试消除重复或管理不善的索引的粗心实现可能会失败。 

## 方法

 最直接的方法是使用标准的基于比较的排序算法。 您可以通过重复比较相邻元素并在它们无序时交换它们来实现冒泡排序或插入排序。 这是可行的，因为数组很小，但在最坏的情况下，它需要大约 n² = 100² = 10,000 次比较和交换，这对于这个问题来说仍然是可以接受的。 此方法在概念上很简单：遍历数组，比较对，如果需要则交换，重复直到没有交换发生。 它对于任何输入都是正确的，但对于较大的数组来说扩展性很差。 

一种更优雅的方法利用了所有数字都是 1 到 100 范围内的整数这一事实。这允许使用计数排序。 我们不是重复比较数字，而是计算每个数字出现的次数，然后通过将每个数字写入计算的次数来重建排序数组。 这将算法简化为 O(n + m)，其中 m 是数字范围（此处为 100），从而给出确定性且非常快速的解决方案。 

蛮力方法之所以有效，是因为重复比较最终可以正确定位每个元素，但对于较大的数组来说，它的效率较低。 通过观察输入数字是有界和离散的，我们可以将问题简化为线性时间计数练习，在给定约束的情况下这是最佳的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 比较排序（冒泡/插入）| O(n²) | O(1) | O(1) | 已接受 |
 | 计数排序 | O(n + m) | O(米) | 已接受 |

 ## 算法演练

 1. 读取整数_n_以确定数组中元素的数量。 此步骤设置数组存储和循环限制。 
2. 初始化一个列表来存储数组元素，然后从输入中读取每个整数并将其附加到列表中。 这保留了计数排序阶段的原始顺序。 
3. 创建一个大小为 101 的计数数组，并初始化为零。 每个索引代表一个从 1 到 100 的数字，该索引处的值将存储该数字在输入中出现的次数。 
4. 迭代原始数组。 对于每个元素，增加计数数组中相应的索引。 这产生了数字的频率分布。 
5. 初始化一个空结果列表。 从索引 1 到 100 迭代计数数组。对于每个具有非零计数的索引，将索引值追加到结果列表中的次数与其计数相同。 此步骤按排序顺序重建数组。 
6. 打印结果列表，用空格连接数字。 这会产生所需的输出格式。 

工作原理：计数数组保证每个数字在输出中出现的次数与在输入中出现的次数完全相同，并且因为我们按升序索引顺序迭代计数数组，所以结果是排序的。 任意数组元素之间不需要进行比较，并且可以自然地处理重复项。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
arr = [int(input()) for _ in range(n)]

count = [0] * 101
for num in arr:
    count[num] += 1

result = []
for num in range(1, 101):
    result.extend([num] * count[num])

print(" ".join(map(str, result)))
```第一部分使用有效读取输入`sys.stdin.readline`。 使用列表理解立即将数字存储在`arr`。 这`count`大小为 101 的数组允许直接索引，因此`count[num] += 1`增加每个数字的频率。 在重建步骤中，`[num] * count[num]`将数字重复正确的次数，并且`extend`将这些添加到结果列表中。 最后，`map(str, result)`将整数转换为字符串以与空格连接。
