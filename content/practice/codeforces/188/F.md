 ## 解决方案
 ## 问题理解

 任务是取一个正整数并以基数 2 表示它，这意味着我们仅使用系数为 0 或 1 的 2 的幂来重写它。我们需要的不是通常的十进制表示形式，而是需要二进制字符串来告诉我们哪些 2 的幂之和等于该数字。 

例如数字5对应选择4和1，所以它的二进制表示为`101`。 二进制字符串中的每个位置表示总和中是否包含特定的 2 的幂。 

约束非常小，n 最多为 1,000,000。 这立即意味着我们永远不会面临性能问题的危险，即使是直接的位操作或重复的除法。 任何以对数时间甚至在位数上呈线性运行的解决方案就足够了。 由于 1,000,000 的二进制长度最多为 20 位，因此输出本身很小。 

结构上不存在隐藏的极端情况，但一些实施陷阱经常出现。 一个人意外地产生了前导零，例如打印类似的内容`000101`而不是`101`。 另一个问题是，如果使用除以 2 的方法并以错误的顺序附加位，则会错误地反转二进制数字。 第三种是对值1的处理不当，应该直接输出`1`无需任何额外的格式。 

## 方法

 思考这个问题的强力方法是通过重复检查 2 的幂来模拟二进制构造。 可以从 1、2、4、8 等开始，测试每个幂是否适合剩余值，如果适合则减去它。 这种方法是正确的，因为二进制表示本质上是对 2 的幂的贪婪分解。 然而，它是不必要的间接的，并且需要对直到 n 的所有幂进行重复求幂或迭代，这在这里仍然很小，但在概念上效率很低。 

更直接的粗暴方法是重复除以 2。我们将数字除以 2，每次记录余数，并收集位。 这是可行的，因为除以 2 会在每一步提取最低有效位。 问题不在于正确性，而在于输出顺序。 余数是从最低有效位到最高有效位得出的，因此最后必须将它们反转。 

关键的观察结果是，二进制表示正是重复除以 2 时的余数序列。这将问题简化为对数长度的简单循环，对于最大输入最多产生约 20 次迭代。 除了字符串生成器或字符列表之外，我们不需要任何额外的数据结构。

 | --- | --- | --- | --- |
 | 暴力破解（两次扫描的威力）| O(log n) | O(1) | O(1) | 已接受 |
 | 最优（重复除以 2） | O(log n) | O(log n) | 已接受 |

 ## 算法演练

 1. 将输入的整数n作为要转换的数。 
2. 重复将n除以2，同时每次存储余数，因为余数告诉我们当前最低有效位是0还是1。 
3. 每次除法之后，将 n 替换为 n // 2，以便我们转向更高的有效位。 
4. 将每个余数存储在列表中，因为第一个余数对应于最低有效位。 
5. 一旦 n 变为 0，则停止循环，因为所有位均已处理完毕。 
6. 反转收集的余数，因为它们是从最低有效位到最高有效位生成的。 
7. 将它们连接成一个字符串并输出。 

此排序步骤是必要的原因是二进制扩展是位置的。 每个划分从当前最低有效位置提取信息，因此自然生成顺序相对于最终表示是相反的。 

### 为什么它有效

 在每一步中，算法都会将 n 分解为 n = 2q + r，其中 r 为 0 或 1。余数 r 正是当前最低的二进制数字。 通过用 q 替换 n 来删除该数字可以保留剩余数字仍然代表原始值的高阶位的不变性。 重复此操作直到 n 变为零，确保两次贡献的每个幂都被提取一次，因此最终的反转序列是唯一的二进制表示。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())

bits = []

while n > 0:
    bits.append(str(n % 2))
    n //= 2

print(''.join(reversed(bits)))
```该解决方案读取整数，然后使用模 2 重复提取最低有效位。每个提取的位都存储为字符串。 因为这些位是以相反的顺序收集的，所以我们在加入之前在末尾反转列表。 

一个微妙但重要的细节是，当 n 变为 0 时我们停止。如果我们进一步继续，我们将附加前导零，这不是规范二进制表示的一部分。 另一个细节是尽早将位转换为字符串，这简化了最终的连接操作。 

## 工作示例

 ### 示例 1：n = 5

 | 步骤| n | n % 2 | 位|
 | --- | --- | --- | --- |
 | 1 | 5 | 1 | [1] |
 | 2 | 2 | 0 | [1, 0] |
 | 3 | 1 | 1 | [1, 0, 1] |
 | 4 | 0 | 停止| [1, 0, 1] |

 反转后，我们得到`101`。 这证实了该算法从最低有效位向上正确地重建了二进制表示。 

### 示例 2：n = 6

 | 步骤| n | n % 2 | 位|
 | --- | --- | --- | --- |
 | 1 | 6 | 0 | [0]|
 | 2 | 3 | 1 | [0, 1] |
 | 3 | 1 | 1 | [0, 1, 1] |
 | 4 | 0 | 停止| [0, 1, 1] |

 倒车给出`110`，匹配 6 = 4 + 2。 

该跟踪表明，即使最低有效位为零，它仍然可以正确捕获和保存。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(input().strip())

    bits = []
    while n > 0:

 ## 边缘情况

 用于输入`1`，算法从 n = 1 开始，附加`1 % 2 = 1`，然后将 n 减少到 0 并停止。 位列表变为`[1]`，并且反转它仍然会产生`1`。 这证实了单位情况的处理不会产生空输出或额外的填充。 

用于输入`8`，循环产生余数`[0, 0, 0, 1]`。 倒车给出`1000`。 这表明二进制形式的尾随零被正确保留并且不会被过早丢弃。
