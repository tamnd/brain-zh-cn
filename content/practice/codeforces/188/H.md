 ## 解决方案
 ## 问题理解

 输入是描述堆栈操作的字符串。 每个数字的意思是“将此数字压入堆栈”。 每个`+`或者`*`意思是“从堆栈中取出前两个值，应用操作，然后将结果推回”。 

这本质上是评估以逆波兰表示法（后缀表示法）编写的表达式。 堆栈存储中间结果。 每当我们遇到一个运算符时，两个最近可用的值就会成为它的操作数。 

例如，字符串：```
12+3*
```方法：```
push 1
push 2
add -> 3
push 3
multiply -> 9
```最终的答案是处理完所有操作后保留在堆栈顶部的值。 

限制非常小。 操作字符串的长度最多为 20，因此即使效率非常低的方法也会立即运行。 直接模拟对每个字符执行一次堆栈操作，在最坏的情况下仅执行几十次操作。 

主要挑战不是性能，而是正确实现堆栈行为。 

一个容易犯的错误是以错误的顺序使用操作数。 对于加法和乘法，这不会影响结果，因为这两种运算都是可交换的，但在更通用的后缀求值器中，这很重要。 正确的实现仍然应该首先弹出第二个操作数，然后弹出第一个操作数。 

考虑：```
12+
```之前的堆栈`+`是：```
[1, 2]
```运算符使用操作数`1`和`2`，生产`3`。 

当输入仅包含数字而不包含运算符时，会出现另一种边缘情况。 

输入：```
123
```堆栈演变为：```
[1]
[1, 2]
[1, 2, 3]
```答案是最上面的元素，`3`。 假设堆栈始终以一个值结束的解决方案在这里会失败。 

第三种边缘情况是单字符输入。 

输入：```
7
```输出：```
7
```该算法必须正确处理从头到尾仅包含一个元素的堆栈。 

## 方法

 最直接的想法就是完全按照描述来模拟过程。 维护一个堆栈。 当出现数字时，按下其数值。 当出现运算符时，弹出两个值，应用运算，然后推送结果。 

由于输入描述的每个操作都对应于恒定的工作量，因此总运行时间与字符串的长度成正比。 

人们还可以考虑重建由后缀表示法表示的数学表达式，然后对其进行评估。 这是可行的，但它带来了不必要的复杂性。 在求值之前，我们需要构建一个表达式树或将符号转换为另一种形式。 

关键的观察是问题已经告诉我们应该如何执行计算。 堆栈不仅仅是一个实现细节，它是实际的评估机制。 按照字面上的操作立即给出答案。 

由于输入长度最多为 20，因此两种方法都足够快。 直接模拟更简单并且与问题陈述完全匹配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力堆栈模拟 | O(n) | O(n) | 已接受 |
 | 最优堆栈模拟 | O(n) | O(n) | 已接受 |

 对于这个问题，自然模拟已经是最优的。 

## 算法演练

 1. 创建一个空堆栈。 
2. 从左到右处理输入字符串。 
3. 如果当前字符是数字，则将其转换为整数并压入堆栈。 
4. 如果当前字符是`+`，从堆栈中弹出顶部的两个值，将它们相加，然后将结果推回。 

堆栈始终包含足够的值，因为保证输入有效。 
5. 如果当前字符是`*`，从堆栈中弹出顶部两个值，将它们相乘，然后将结果推回。 
6、处理完所有字符后，输出栈顶元素。 

### 为什么它有效

 处理输入的任何前缀后，堆栈将准确包含问题陈述所描述的实际堆栈中存在的值。 数字添加新值，而运算符消耗前两个值并将其替换为运算结果。 由于每个步骤都会准确地重现所需的堆栈行为，因此最终的堆栈状态与预期的执行相同。 因此，最后的顶部元素是所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    stack = []

    for ch in s:
        if ch.isdigit():
            stack.append(int(ch))
        elif ch == '+':
            b = stack.pop()
            a = stack.pop()
            stack.append(a + b)
        else:  # '*'
            b = stack.pop()
            a = stack.pop()
            stack.append(a * b)

    print(stack[-1])

if __name__ == "__main__":
    solve()
```实现直接遵循模拟。 

堆栈由 Python 列表表示。 追加对应于推送操作，并且`pop()`删除当前顶部元素。 

当遇到运算符时，代码会删除两个元素。 第一次弹出给出第二个操作数，第二次弹出给出第一个操作数。 尽管加法和乘法是可交换的，但保留正确的操作数顺序是很好的做法，并使实现与后缀求值总体上一致。 

最后，问题要求获取最顶层的堆栈元素。 该值存储在`stack[-1]`。

 ## 边缘情况

 考虑输入：```
123
```执行：```
push 1 -> [1]
push 2 -> [1, 2]
push 3 -> [1, 2, 3]
```该算法输出顶部元素，`3`。 它并没有错误地假设堆栈中必须保留一个元素。 

考虑输入：```
7
```执行：```
push 7 -> [7]
```不处理任何运算符。 最终的顶部元素是`7`，直接打印出来。 

考虑输入：```
12+
```执行：```
push 1 -> [1]
push 2 -> [1, 2]
+ -> [3]
```该运算符使用两个最新值并推入它们的总和。 结果堆栈包含一个值，`3`，这成为答案。 

这些情况涵盖了最有可能暴露有关堆栈大小或运算符处理的错误假设的情况，并且模拟可以自然地处理所有这些情况。
