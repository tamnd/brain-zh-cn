 ## 解决方案
 ## 问题理解

 罗马有一个正整数的集合，他对十进制数字仅由 4 和 7 组成的数字着迷。这些数字被称为幸运数字。 任务是从他的集合中确定有多少个数字最多有 _k_ 个幸运数字。 输入给出了集合的大小 _n_、允许的最大幸运数字数 _k_，然后是 _n_ 数字本身。 输出是一个整数：满足幸运数字约束的数字计数。 

约束条件适中：_n_ 和_k_ 都最多为 100，并且每个数字最多可达 10^9。 这意味着我们可以单独处理每个数字并检查每个数字，而无需担心性能问题。 简单的逐位检查是可行的，因为在最坏的情况下，100 个数字（每个数字最多 10 个数字）会导致大约 1,000 次操作。 边缘情况包括没有幸运数字的数字、完全由幸运数字组成的数字或 _k_ 大于最大数字中的位数的情况。 例如，如果 _n_ = 3，_k_ = 1，数字为 4, 7, 47，则正确输出为 2，因为 47 有两个幸运数字并且超过了_k_。 粗心的实现可能会错误计算数字或忘记与 _k_ 进行比较，从而给出错误的总数。 

## 方法

 暴力方法很简单。 遍历罗马的每个号码，并计算每个号码有多少位是幸运的。 如果计数不超过 _k_，则增加运行总计。 这是有效的，因为每个数字最多有 10 个数字，并且最多有 100 个数字，产生大约 1,000 个数字的检查。 该算法在结构上是正确的，因为我们明确地计算了幸运数字并将它们与阈值进行比较。 由于输入限制较小，性能不是问题。 

不需要更快的渐近解，因为暴力方法已经满足约束。 唯一可能的优化是风格上的：我们可以将数字转换为字符串，并使用生成器表达式来计算一行中的幸运数字，而不是使用循环，但底层逻辑不会改变。 这个问题本质上是关于仔细的迭代和计数，而不是算法的复杂性。

 ## 算法演练

 1. 从输入中读取整数_n_和_k_，并读取数字列表。 
2. 初始化计数器`result`为零。 这将保存满足幸运数字条件的数字计数。 
3. 迭代列表中的每个数字。 
4. 对于每个数字，初始化一个本地计数器`lucky_count`为零。 
5. 检查当前号码的每一位。 如果数字是 4 或 7，则递增`lucky_count`。 
6. 检查完所有数字后，进行比较`lucky_count`到_k_。 如果`lucky_count`≤_k_，增量`result`。 
7. 处理完所有数字后，输出`result`。 

为什么有效：在每一步中，我们都会明确计算每个数字的幸运数字，并检查它们是否保持在允许的阈值内。 不变的是`result`始终准确地反映迄今为止处理的满足条件的数字的计数。 由于每个数字都会被检查并且与 _k_ 的比较是准确的，因此不会有任何数字被误算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
numbers = list(map(int, input().split()))
result = 0

for num in numbers:
    lucky_count = sum(1 for digit in str(num) if digit == '4' or digit == '7')
    if lucky_count <= k:
        result += 1

print(result)
```该解决方案使用有效地读取输入`sys.stdin.readline`处理标准的竞争性编程输入速度。 每个数字都会转换为字符串，以便我们可以单独检查数字。 生成器表达式`sum(1 for digit in str(num) if digit == '4' or digit == '7')`干净地计算幸运数字并避免手动循环。 比较`k`确保只有满足条件的数字才会对最终结果产生影响。 使用整数可以避免任何溢出风险，并且较小的数字可以保证没有性能瓶颈。

 ## 边缘情况

 对于超过_k_的单个数字，例如`n=1, k=0, numbers=[4]`，算法正确地计算出 1 个幸运数字，将其与 0 进行比较，并跳过对结果进行递增，产生输出 0。对于最大尺寸的数字，例如`n=100, k=100, numbers=[777777777]*100`，每个数字有9位数字，都是幸运的。 每个数字的总和为 9，即 ≤ 100，因此对所有数字进行计数，输出为 100。该算法正确处理零、边界和最大输入，不会出现差一错误。
