 ## 解决方案
 ## 问题理解

 我们得到一个有向友谊图$n$用户，其中每个用户将其他一些用户列为朋友。 重要的细节是，友谊并不能保证是相互的。 如果用户$u$列表$v$，这并不意味着$v$列表$u$。 

任务是检测所有“隐藏的友谊”，即所有有序对$(u, v)$这样$u$考虑$v$一个朋友但是$v$不考虑$u$一个朋友。 用图术语来说，我们正在寻找邻接列表中不互惠的所有有向边。 

输入本质上是一个有向图的邻接列表表示，其顶点从 1 到$n$。 输出需要列出不存在反向边的每个有向边，并计算存在多少个这样的边。 

自从$n \le 100$，边的总数最多约为$n^2$，最多为 10,000。 这足够小，任何检查邻接性的解决方案$O(1)$甚至$O(n)$每条边都会足够快。 一个天真的$O(n^3)$方法也可以通过，但没有必要。 

一个微妙的点是，每个邻接列表中不存在重复项，但列表之间的不对称性正是定义答案的原因。 另一个边缘情况是朋友为零的用户，这不应该产生任何传出隐藏边缘，但仍可能作为目标出现在其他人的列表中。 

一个常见的错误是假设对称性或仅检查一个方向一次而不验证相反列表中的存在性。 另一个错误是忘记输出必须包括所有不对称边缘，而不仅仅是同时在两个方向上不同的用户对。 

例如，如果用户1列出了2，但用户2没有列出1，我们必须输出(1, 2)。 如果用户 2 列出了 1 但 1 没有列出 2，我们也输出 (2, 1)。 这些是独立的定向检查，而不是单一的无向不一致。 

## 方法

 最简单的想法是迭代每个用户$u$，以及每一位朋友$v$在$u$的列表，检查是否$u$出现在$v$的清单。 如果没有，那么$(u, v)$是一种隐藏的友谊。 

在暴力实现中，检查成员资格$v$使用线性搜索的列表导致$O(n)$每张支票。 由于每个用户最多可以拥有$O(n)$朋友们，我们对每条边进行检查，总复杂度就变成了$O(n^3)$在最坏的情况下。 和$n = 100$，这仍然是可以接受的，但结构上效率低下且不必要。 

关键的改进来自于将每个邻接列表表示为哈希集。 这将会员查询转化为平均查询$O(1)$运营。 然后，对于每个有向边$u \to v$，我们简单地检查是否$u \in adj[v]$。 如果没有，我们输出它。 

这是可行的，因为问题简化为有向图中的边存在查询，并且基于散列的集合提供恒定时间的成员资格检查，将三重嵌套结构折叠为二次扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（列表搜索）|$O(n^3)$|$O(n^2)$| 已被接受但效率低下 |
 | 哈希集查找 |$O(n^2)$|$O(n^2)$| 已接受 |

 ## 算法演练

 1. 读取每个用户的邻接表并将其作为一个集合存储。 这确保了在验证互惠时快速进行成员资格检查。 
2. 初始化一个空列表来存储答案。 
3. 对于每个用户$u$，迭代每个朋友$v$在他们的集合中。 这枚举了图中的所有有向边。 
4. 对于每对$(u, v)$，检查是否$u$存在于邻接集中$v$。 如果没有，请追加$(u, v)$到答案列表。 这可以直接识别丢失的反向边缘。 
5. 处理完所有用户后，输出存储的对的总数，然后输出每对。 

步骤 4 背后的推理是有向图中的互易性正是条件$u \in adj[v]$。 如果不满足这一条件，则意味着边缘是单边的。 

### 为什么它有效

 我们保持每个候选对的不变性$(u, v)$直接来自输入中的显式邻接关系。 如果反向关系不存在，我们只输出一对。 由于我们对每个有向边精确扫描一次并独立检查其逆边是否存在，因此不会错过任何隐藏的友谊，并且不会错误地包含有效的互易边。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
adj = [set() for _ in range(n + 1)]

for i in range(1, n + 1):
    data = list(map(int, input().split()))
    cnt = data[0]
    for v in data[1:]:
        adj[i].add(v)

res = []

for u in range(1, n + 1):
    for v in adj[u]:
        if u not in adj[v]:
            res.append((u, v))

print(len(res))
for u, v in res:
    print(u, v)
```该实现将每个邻接列表存储为一个集合，以便成员资格检查的时间恒定。 外循环遍历所有用户，内循环遍历他们声明的朋友。 关键的决定是条件`u not in adj[v]`，它直接编码不对称性要求。 

一个常见的陷阱是忘记将列表转换为集合，这会默默地降低二次循环内二次成员资格检查的性能。 另一个微妙的问题是迭代原始输入列表而不保持索引一致性，这可能会导致相差一错误。 这里我们显式分配`n + 1`以便用户编号与索引对齐。

 ## 边缘情况

 关键的边缘情况是节点没有传出边缘。 例如，如果用户 2 有一个空列表，它永远不会产生外出配对，但仍然可能是其他人隐藏友谊的目标。 该算法自然地处理这个问题，因为我们只迭代现有的邻接条目。 

另一种情况是完全不对称的链，其中每个边都指向前方但从不向后。 该算法将输出所有边，因为每次反向查找都会失败。 这证实了正确地保留了方向性并且没有假定隐式对称性。 

最后一个微妙的情况是嵌入在较大图中的相互对。 例如，如果 1 列出 2，2 列出 1，但 1 也列出 3，而 3 不列出 1，则只应出现 (1,3)。 该算法独立地隔离每个有向边，因此不相关的相互边的存在不会影响正确性。
