 ## 解决方案
 ## 问题理解

 给定一个由小写字母组成的字符串，我们可以将其所有字符拆分为恰好 k 个非空组。 在每个组内，我们可以任意重新排序字符，因此每个组实际上只是一组字母，稍后我们将其排序为字符串。 

一旦所有 k 个字符串形成，我们就按字典顺序查看它们并取最大的一个。 我们的目标是分配字符，使这个最差的字符串在字典中尽可能小。 

关键的自由在于我们不是分割序列，而是分布多重集。 这消除了任何位置限制，并使问题完全与频率和顺序有关。 

这些约束强制每个测试用例采用线性或近线性解决方案。 由于测试中的总 n 最多为 10^5，因此每个测试用例的 O(n log n) 或总体 O(n) 左右的任何解决方案都是可以接受的。 任何涉及重复模拟分布或指数分配的事情都是立即不可能的。 

当 k 等于 n 时，会出现微妙的边缘情况。 在这种情况下，每个字符串只包含一个字符，因此答案就是字符串中的最大字符。 另一种边缘情况是当 k 等于 1 时，答案只是排序后的字符串本身，因为所有字符都必须进入一组。 

当字符串具有占主导地位的最小字符时，会出现更有趣的极端情况。 例如，如果大多数字符是“a”，则均匀或不均匀地分布它们会改变哪个字符串在字典顺序上变得最大，并且如果不遵守排序约束，则天真的贪婪分组可能会失败。 

## 方法

 强力解释将尝试将 n 个字符的所有可能分布分配到 k 个非空组中。 即使我们忽略内部排列，这也意味着将每个字符分配给 k 个桶之一，从而给出 k^n 种可能性。 这远远超出了任何限制。 

关键的观察是字典顺序是由字符串不同的最早位置决定的。 为了最小化最大字符串，我们希望所有组的第一个字符尽可能小，并且我们希望控制第一个不同位置的“大”。 

对字符串进行排序可以揭示最佳解决方案的结构。 一旦排序，我们就可以有效地决定如何将排序序列切割成 k 个部分，因为任何最佳排列都可以转换为其中组对应于排序字符串的连续段的排列，而不会恶化最大值。 

从这里开始，出现了两种情况。 如果最小的 k 个字符并不全部相同，则答案只是排序顺序中的第 k 个字符，因为我们可以将最小的 k 个字符分配为 k 个字符串的第一个字母，而其他所有内容仅影响尾随位置。 如果前 k 个字符相同，则我们被迫均匀分布它们，并且答案变为该字符加上最佳分布的剩余后缀，这减少了以任意顺序附加所有剩余字符。 

更深入的见解是，一旦我们修复了每个组的第一个字符，剩余的分布就不再影响最大值，除非它比必要的更早引入了按字典顺序排列的更大的前缀。 这会在排序后产生干净的确定性结构。

 ## 算法演练

1. 按非降序对字符串进行排序。 排序很有用，因为字典最小化总是更早地选择较小的字符，并且任何最佳排列都可以按排序顺序进行推理。 
2. 如果k等于1，则返回整个排序后的字符串。 没有分配选择，因此单个字符串是固定的。 
3. 检查排序字符串中的第 k 个字符（0-索引 k-1）。 如果这个字符严格大于第一个字符，我们就知道前 k 个位置中至少存在一个严格更大的字符。 
4. 在这种情况下，返回第 k 个字符作为答案。 原因是我们可以将前 k 个最小的字符指定为 k 个字符串的起始字符，其中按字典顺序最大的字符串将从第 k 个最小的字符开始。 
5. 如果前 k 个字符全部相同，那么我们不能通过在它们之间进行不同的分配来减少最大值。 我们在前 k-1 个字符串中的每个字符串中放置一个字符，然后将其余的字符放入第 k 个字符串中，这将成为唯一的非平凡字符串。 
6. 在第二种情况下，答案是排序字符串中从索引 k-1 开始的后缀。 由于所有前 k-1 个字符都是相同的，因此后缀的顺序决定了词典最大值。 

### 为什么它有效

 该算法依赖于字典顺序比较是在第一个不同位置决定的事实。 当我们排序时，我们确保任何较早的字符都不会比后面的字符更差。 影响最大字符串的唯一方法是通过作为任何组的第一个元素出现的最小字符。 一旦前 k 个字符被固定，所有其他分配只会将字符附加到已经具有较小或相等前缀的字符串中，因此它们无法更改最大值的标识，除非所有前缀都相等，在这种情况下，后缀完全决定了答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = sorted(input().strip())

        if k == 1:
            print("".join(s))
            continue

        if s[k-1] != s[0]:
            print(s[k-1])
        else:
            # all first k characters are equal
            print("".join(s[k-1:]))

if __name__ == "__main__":
    solve()
```该解决方案首先对字符串进行排序，以便我们可以直接推断出最小的可用字符。 对 k 等于 1 的检查处理不发生分布的简单情况。 第一个和第 k 个字符之间的比较决定了我们是否可以以产生不同起点的方式将最小的字符分开。 如果它们不同，则第 k 个字符将成为最差组的限制因素。 如果它们相同，则所有早期组都以相同的方式开始，迫使剩余的后缀定义最差的字符串。 

一个微妙的点是我们从来没有显式地构造 k 个字符串。 推理保证了最优分区的结构，因此不需要直接模拟。

 ## 边缘情况

 当 n 等于 k 时，对字符串进行排序并正确返回 s[k-1] 会给出最大字符，因为每个字符都是独立的。 例如，输入`cba`k=3 变为`abc`，并且 s[2] 是`c`，这是正确的。 

当所有字符都相同时，例如`aaaaa`对于任意 k，算法进入等前缀分支。 k-1 的后缀仍然是`a...a`，因此每个组都有相同的字符串，并且最大值不变。 

当字符高度倾斜时，例如`zzzyyy`，排序给出`yyyzzz`。 对于 k=2，由于前缀检查中 s[1] 等于 s[0]，因此我们返回从索引 1 开始的后缀，即`yyzzzz`在组术语中，字典顺序最大的字符串正确地变为`zzz`。
