 ## 解决方案
 ## 问题理解

 我们有一个（N × M）网格。 每个单元包含在撞击岩石之前可以在该位置挖掘的最大深度。 我们必须准确选择（S）个细胞来形成池。 所选单元必须通过共享边连接，并且池具有统一的深度。 

如果所选单元格仅允许挖掘至深度 (7)，则整个水池的深度不能超过 (7)。 因此，对于任何连接的 (S) 单元集，其可实现的深度是这些单元中的最小深度。 任务是最大化该最小值。 

考虑候选深度 (D) 的一个有用方法是丢弃值小于 (D) 的每个单元格。 剩下的单元正是可以建造深度池（D）的地方。 问题是这些剩余的单元是否包含至少具有 (S) 个单元的连通分量。 

单元总数最多为 (10^6)，因此重复检查整个网格以获取许多候选深度的算法过于昂贵。 可以有 (10^6) 个不同的深度值，对每个可能的深度进行 (O(NM)) 扫描，算法为 (O((NM)^2))，在最坏的情况下将达到大约 (10^{12}) 个单元检查。 除了订购电池的成本之外，我们还需要一些接近线性的东西。 

尺寸本身也可能非常大。 一个 (N=M=1000) 的网格已经包含 (10^6) 个单元格，并且任一维度允许大到 (10^6)。 这排除了依赖于 (N^2)、(M^2) 或重复全网格遍历的算法。 内存限制还意味着应尽可能避免为每个单元存储大型 Python 对象。 

在一些边缘情况下，表面上正确的解决方案可能会失败。 

对于 (S=1)，除了单个单元之外不需要连接。 例如，```
1 1 1
42
```有答案（42）。 始终尝试将单元连接到邻居的解决方案会错误地得出不存在池的结论。 

另一个重要的情况是当高价值的电池断开连接时。 考虑```
2 1 3
10 1 10
```答案是（1），而不是（10）。 有两个深度为 (10) 的单元，但它们被深度为 (1) 的单元隔开。 简单地取 (S) 最大值而不考虑连通性的解决方案将返回错误的结果。 

相反的情况也很重要。 如果一个连通分量包含超过 (S) 个单元，我们就可以使用其中的 (S) 个单元。 例如，```
3 1 5
8 8 8 8 8
```答案为 (8)，即使该组件包含五个单元格。 要求组件具有精确 (S) 个单元的解决方案会错误地拒绝它。 

最后，当(S=N\cdot M)时，每个单元都必须属于池。 例如，```
4 2 2
5 7
8 6
```答案为 (5)，因为整个网格的最小深度为 (5)。 一旦发现大的高值区域就停止的方法可能会忽略这样一个事实：当 (S) 等于整个网格大小时，池必须包含每个单元格。 

## 方法

 直接的方法是尝试所有可能的池深度。 对于候选深度 (D)，我们仅保留值至少为 (D) 的单元格，对这些单元格进行洪水填充，并检查任何连接的组件是否至少具有 (S) 个单元格。 这是正确的，因为此类组件中的每个单元都可以支持深度 (D)，并且任何至少具有 (S) 个单元的连接组件都包含恰好 (S) 个单元的连接子集。 

问题是候选深度的数量。 可以有多达 (NM) 个不同的值。 在最坏的情况下，一次洪水填充需要 (O(NM)) 时间，因此检查每个不同的深度需要 (O((NM)^2))。 对于 (NM=10^6)，这可能是 (10^{12}) 个单元格访问。 

我们可以通过从最大到最小处理深度来改进这个想法，而不是独立检查每个深度。 

假设我们已经激活了深度至少为 (D) 的每个单元。 此时，活动单元恰好形成与深度池 (D) 相关的图形。 当我们降低阈值时，新激活的细胞就会简单地添加到该图中。 连接性只会增长，因此我们永远不需要从头开始重新计算任何连接的组件。 

这正是不相交集并集结构的设计目的。 每个激活的单元都作为其自己的组件开始。 每当一个激活的细胞有一个激活的邻居时，我们就会合并它们的组成部分。 DSU 存储每个组件的大小，因此在激活单元后我们可以立即检查其组件是否已达到大小（S）。 

组件达到尺寸 (S) 的第一个深度就是答案。 按降序处理意味着每个先前激活的单元格的深度至少为当前深度。 因此，在深度 (D) 处达到大小 (S) 的组件给出了有效的深度池 (D)，而没有更大的深度可以支持 (S) 连接的单元，因为我们已经提前停止了。 

有一个特定于 Python 的实现细节值得仔细处理。 网格可以包含 (10^6) 个单元格，因此存储元组，例如`(depth, row, column)`产生大量的内存开销。 相反，每个单元都由一个整数表示，该整数包含其深度及其展平单元索引。 由于 (NM\le10^6<2^{20})，低 20 位足以用于索引。 其余位存储深度。 Python 的内置排序可以有效地对这些打包整数进行排序。 

DSU 数组使用以下方式存储`array('i')`，它每个条目使用四个字节，而不是 Python 更大的每整数对象表示形式。 活动单元格存储在`bytearray`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O((NM)^2)) | (O(NM)) | 太慢了|
 | 最佳| (O(NM\log(NM))) | (O(NM)) | 已接受 |

 ## 算法演练

 1. 将二维网格展平为从 (0) 到 (NM-1) 的索引。 将每个单元格存储为一个包含其深度和扁平索引的压缩整数。 按降序对这些整数进行排序可以得到从最深到最浅的单元格。 
2. 创建一个 DSU 结构，每个单元都有一个最初独立的组件。 还创建一个`active`大批。 仅当在下行扫描中到达某个单元后，该单元才处于活动状态。 
3. 按深度降序处理单元格。 当遇到一个单元格时，激活它并使其分量大小等于 1。 
4. 检查单元格的四个可能的网格邻居。 对于每个已处于活动状态的邻居，合并两个 DSU 组件。 我们只合并活动邻居，因为不活动邻居的深度小于当前阈值，不能属于当前深度的池。 
5. 对新激活的单元进行所有可能的联合后，检查其 DSU 组件的大小。 如果该大小至少为 (S)，则返回当前单元格的深度。 
6. 继续直至组分到达 (S) 个单元格。 这样的组件完全由深度至少为报告值的单元组成，并且它是连接的。 由于它至少包含 (S) 个单元，因此我们可以从中准确选择 (S) 个连接的单元。 

为什么具有超过 (S) 个单元的连通分量总是包含正好 (S) 个单元的连通子集？ 从任意顶点开始，重复添加属于该组件的相邻顶点。 由于组件已连接，因此该过程可以继续，直到恰好选择了 (S) 个顶点。 

整个扫描背后的不变量是，在处理深度 (D) 之前，每个活动单元至少具有深度 (D)，并且 DSU 分量正是这些活动单元的连接分量。 当当前单元被激活时，仅需要添加到已经活动的邻居的边，因此不变量保持为真。 因此，当一个组件首先到达（S）个单元格时，它代表该深度的可行池。 由于深度是从最大到最小处理的，因此第一个深度是最大的。 

## Python 解决方案```python
import sys
from array import array

input = sys.stdin.readline

SHIFT = 20
MASK = (1 << SHIFT) - 1

def solve():
    S, N, M = map(int, input().split())
    total = N * M

    # Pack (depth, index) into one integer.
    # The lower 20 bits store the index because total <= 10^6 < 2^20.
    cells = []
    append = cells.append

    idx = 0
    for _ in range(N):
        row = map(int, input().split())
        for depth in row:
            append((depth << SHIFT) | idx)
            idx += 1

    cells.sort(reverse=True)

    parent = array('i', range(total))
    size = array('i', [1]) * total
    active = bytearray(total)

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a = find(a)
        b = find(b)

        if a == b:
            return a

        if size[a] < size[b]:
            a, b = b, a

        parent[b] = a
        size[a] += size[b]
        return a

    for code in cells:
        depth = code >> SHIFT
        idx = code & MASK

        active[idx] = 1
        root = idx

        row = idx // M
        col = idx - row * M

        if row > 0:
            other = idx - M
            if active[other]:
                root = union(root, other)

        if row + 1 < N:
            other = idx + M
            if active[other]:
                root = union(root, other)

        if col > 0:
            other = idx - 1
            if active[other]:
                root = union(root, other)

        if col + 1 < M:
            other = idx + 1
            if active[other]:
                root = union(root, other)

        root = find(root)

        if size[root] >= S:
            print(depth)
            return

if __name__ == "__main__":
    solve()
```输入是逐行读取的，因此程序永远不会创建所有输入标记的巨大列表。 每个深度立即与其展平位置打包在一起并附加到`cells`。 

表达式`(depth << SHIFT) | idx`将两条信息存储在一个整数中。 由于最大可能的单元数为 (10^6)，因此 20 位就足够了`idx`。 因此，按降序对打包值进行排序主要按深度排序，这正是 DSU 扫描所需的顺序。 

这`active`字节数组与 DSU 是分开的。 仅 DSU 父值无法告诉我们某个单元是否已被激活，因为每个单元从一开始就有一个父单元。 字节数组让我们测试邻居是否属于当前阈值图。 

网格逐行展平。 对于索引`idx`，上面的单元格是`idx - M`，下面的单元格是`idx + M`，左边的单元格是`idx - 1`，右边的单元格是`idx + 1`。 行和列检查可防止边缘缠绕。 特别是，检查`col > 0`使用前`idx - 1`防止一行的第一个单元格错误地连接到前一行。 

DSU 使用大小联合和路径压缩。 这两个操作实际上都是常数时间摊销，更准确地说是 (O(\alpha(NM)))，其中 (\alpha) 是反阿克曼函数。 

该代码检查涉及当前单元格的所有并集后的组件大小。 这一顺序很重要，因为单元格可能连接多个先前独立的组件，而最终合并的组件的大小必须与 (S) 进行比较。 

Python 整数不会溢出，因此压缩表示是安全的。 最大的打包值低于 (10^8\cdot2^{20}+2^{20})，这很容易在 Python 的整数范围内。 

## 工作示例

 ### 示例 1

 输入是```
1 2 4
9 7 7 9
7 8 8 7
```展平的网格是`[9, 7, 7, 9, 7, 8, 8, 7]`。 由于(S=1)，第一个激活的单元已经形成有效组件。 

| 激活深度| 细胞索引 | 联合之后的组件 | 最大相关尺寸 | 决定|
 | --- | --- | --- | --- | --- |
 | 9 | 0 |`{0}`| 1 | 停止|

 第一个单元格的深度为 (9)，因此答案为 (9)。 

这演示了 (S=1) 边界情况。 与其他单元的连通性是无关紧要的，因为单个单元已经是一个连通集。 

### 示例 2

 输入是```
2 2 4
9 7 7 9
7 8 8 7
```这里（S=2）。 深度为 (9) 的两个单元格的索引为 (0) 和 (3)，并且它们不相邻。 深度为 (8) 的两个单元格为索引 (6) 和 (5)，并且它们是相邻的。 

| 激活深度| 细胞索引 | 新工会| 包含单元格的组件尺寸 | 决定|
 | --- | --- | --- | --- | --- |
 | 9 | 3 | 无 | 1 | 继续 |
 | 9 | 0 | 无 | 1 | 继续 |
 | 8 | 6 | 无 | 1 | 继续 |
 | 8 | 5 | (5\左右箭头6) | 2 | 停止|

 当索引 (5) 被激活时，它与索引 (6) 相邻，因此两个深度 (8) 单元格形成大小 (2) 的组件。 我们在深度 (8) 找到了一个有效的池。 

深度 (9) 的单元无法生成大小 (2) 的池，因为它们属于不同的组件。 这说明了为什么仅仅取最大值是不够的，以及为什么必须显式地保持连接性。

 ## 边缘情况

 当第一个小区被激活时，立即处理单小区情况。 为了```
1 1 1
42
```该单元具有深度 (42)，成为大小为 (1) 的活动组件，并且由于 (S=1)，算法返回 (42)。 不需要邻居。 

对于断开的高价值单元，请考虑```
2 1 3
10 1 10
```两个深度 (10) 的单元首先被激活，但两个单元都没有活动的邻居，因此两个组件都保持大小 (1)。 然后，深度 (1) 的中间单元被激活并连接两侧，产生大小为 (3) 的一个组件。 此时组件的大小至少为 (S=2)，因此答案为 (1)。 该算法正确地拒绝了一对诱人但无效的孤立深度 (10) 单元。 

当一个分量大于（S）时，算法会故意检查`>= S`而不是`== S`。 为了```
3 1 5
8 8 8 8 8
```前三个相邻单元已形成恰好三个单元的连通分量，因此算法返回 (8)。 如果在检查之前激活了更多的单元格，则大小为 4 或 5 的分量仍然有效，因为我们可以采用恰好三个单元格的连接子集。 

当（S=N\cdot M）时，直到每个单元都被激活后才能接受阈值。 为了```
4 2 2
5 7
8 6
```深度为 (8)、(7) 和 (6) 的单元首先被激活，但它们的组件大小只有 3。 最终深度 (5) 单元连接该组件，使其大小为 4。 然后算法返回(5)，这正是整个网格的最小深度。 

网格边界检查也很重要。 在行主表示中，一行的最后一个单元格在数字上与下一行的第一个单元格相邻，但这些单元格在网格中不水平相邻。 的条件`col`防止此类错误连接。 相似地，`row > 0`和`row + 1 < N`防止网格外的垂直访问。 

降序排列使第一个成功的 DSU 组件成为最佳组件。 在深度 (D) 处，每个活动单元至少具有 (D) 容量。 如果某个组件达到 (S)，则存在深度池 (D)。 任何更大的深度都会被更早地处理，并且无法产生这样的组件，因此没有跳过更好的答案。
