 ## 解决方案
 ## 问题理解

 将每个城市视为一个顶点，将每条道路视为无向加权边。 城市（v）有一个额外的延迟（T_v）：一旦火势到达（v），城市不会立即完全烧毁。 又需要 (T_v) 秒。 

最初，多个城市在时间 (0) 被点燃。 对于每个城市，我们需要该城市完全烧毁的确切时间。 

假设城市（u）在时间（D_u）完全被烧毁，并且从（u）到（v）有一条长度为（w）的道路。 火可以在时间 (D_u+w) 到达 (v)，然后 (v) 需要另外 (T_v) 秒才能完全燃烧。 因此，这条路线将使（v）完全烧毁

 [
 D_u+w+T_v。 
]

 对于最初着火的城市，在火到达它之前没有道路经过，所以它的燃烧时间很简单

 [
 D_s=T_s。 
]

 该图表最多可包含 (10^5) 个城市和 (10^5) 条道路。 在这样的规模下，城市数量的任何平方都已经太昂贵了。 即使扫描所有道路 (10^5) 次也需要大约 (10^{10}) 次邻接检查，远远超出一秒的限制。 我们需要一个接近 (O((N+M)\log N)) 的算法。 

道路长度和所有 (T_i) 值均为正值，因此所有时间均为非负值。 该图是相连的，因此每个城市最终都会被烧毁。 

有几种边缘情况很容易导致错误的答案。 

首先，最初被点燃的城市在时间 (0) 时并未完全燃烧。 例如：```
2 1 1
1 2 5
7 3
1
```正确的输出是```
7
15
```城市 1 在时间 (0) 开始燃烧，在时间 (7) 结束，然后火势才会在 (5) 秒内传播到城市 2。然后城市 2 还需要 (3) 秒。 将源距离初始化为零的实现将错误地获得 (0) 和 (8)。 

其次，每个中间城市的燃烧延迟很重要。 考虑：```
2 1 1
1 2 5
10 1
1
```正确的输出是```
10
16
```大火花费 (10) 秒燃烧城市 1，传播 (5) 秒，然后花费 (1) 第二次燃烧城市 2。将问题视为普通最短路径并仅添加目的地 (T_v) 将给出 (6)，这是错误的，因为城市 1 必须在火势蔓延之前完成燃烧。 

第三，可能有几个最初着火的城市。 最早到达一座城市的人决定了它的答案。 例如：```
3 2 2
1 2 10
2 3 1
1 1 1
1 3
```正确的输出是```
1
3
1
```(1)秒后从城市3到达城市2，然后又需要(1)秒燃烧，所以它的答案是(2)，实际上是完整的输出```
1
2
1
```仅从第一个源开始的解决方案将错过这条更快的路线。 

最后，平行道路必须单独对待。 样本 2 包含连接同一对城市的多条不同长度的道路。 这样的最短路径可以完全改变答案，因此实现一定不能在不保留最小边的情况下折叠平行边。 

## 方法

 一种直接的方法是分别处理每个最初燃烧的城市。 对于一个源，我们可以运行一种最短路径算法，其从 (u) 到 (v) 的转换成本

 [
 w(u,v)+T_v。 
]

 源以距离 (T_s) 开始。 这给出了来自该特定源的正确燃烧时间，在处理所有 (K) 个源之后，我们为每个城市获取最小答案。 

这种方法是正确的，但它几乎对每个源重复整个图搜索。 Dijkstra 运行需要 (O((N+M)\log N))，因此处理所有源的成本

 [
 O(K(N+M)\log N)。 
]

 在最坏的情况下（K=N=M=10^5），算法甚至可以在考虑堆操作之前粗略地检查（2KM=2\cdot10^{10}）邻接条目。 这对于时间限制来说太过分了。 

关键的观察结果是所有来源都使用完全相同的图和相同的转换规则。 我们实际上并不关心哪个源产生了最佳路径。 我们只关心每个城市最早可能的燃烧时间。 

这正是 Dijkstra 可以同时从多个来源开始的情况。 不要从每个源运行一个 Dijkstra，而是用自己的值 (T_s) 初始化每个最初燃烧的城市，将它们全部放入相同的优先级队列中，让它们竞争到达剩余的城市。 

对于具有最终燃烧时间 (D_u) 的当前城市 (u)，遍历长度为 (w) 到 (v) 的边会产生候选城市

 [
 D_u+w+T_v。 
]

 数量 (w+T_v) 始终为正，因此生成的状态图具有非负边成本，并且 Dijkstra 的贪婪选择仍然有效。 

蛮力方法之所以有效，是因为 Dijkstra 可以处理每个单独的源，但当有多个源时，它会失败，因为它会重复相同的工作。 所有源都可以参与一个最短路径计算这一观察结果让我们可以用一个多源 Dijkstra 替换 (K) Dijkstra 运行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个源运行 Dijkstra 一次 | (O(K(N+M)\log N)) | (O(N+M)) | 太慢了|
 | 多源 Dijkstra | (O((N+M)\log N)) | (O(N+M)) | 已接受 |

 ## 算法演练

 1. 将每条道路存储在邻接表中。 对于 (u) 和 (v) 之间长度为 (w) 的道路，请将 ((v,w)) 添加到 (u) 的列表，将 ((u,w)) 添加到 (v) 的列表，因为该道路是无向的。 
2. 创建一个数组（dist），其中（dist[v]）表示城市（v）被完全燃烧的最早时间。 最初，每个值都是无穷大，因为我们还没有找到到达该城市的路线。 
3. 对于每个最初点燃的城市，设置

 [
 距离[s]=T_s。 
]

 使用键（T_s）将每个这样的城市推入优先级队列。 

该值是 (T_s)，而不是零，因为城市在零时间开始燃烧，但只有在其自身的燃烧延迟之后才完全燃烧​​。 

1. 反复从优先队列中移除暂定燃烧时间最小的城市（u）。 

如果提取的值大于当前值（dist[u]），则丢弃它。 这是由更早、更糟糕的松弛创建的陈旧堆条目。 

1. 对于从 (u) 到 (v) 的每条长度为 (w) 的道路，计算

 [
 候选=dist[u]+w+T_v。 
]

 第一项是（u）燃烧完成的时间，第二项是火穿过马路所需的时间，第三项是燃烧（v）所需的时间。 

1. 如果候选值小于 (dist[v])，则将 (dist[v]) 替换为候选值，并将新的对推入优先级队列。 
2. 当优先级队列为空时，每个城市都有其最短可能的燃烧时间，因为图是连通的。 按城市顺序输出值。 

### 为什么它有效

不变的是，每当 Dijkstra 永久处理一个城市 (u) 时，(dist[u]) 是 (u) 从任何最初点燃的城市中可能完全燃烧的最短时间。 

考虑从初始源到 (u) 的任何可能路线。 源贡献自己的（T）值，每条道路贡献自己的长度，源之后进入的每个城市贡献自己的（T）值。 因此，每条路线完全对应于辅助有向图中的一条路径，其从 (u) 到 (v) 的转换具有成本 (w(u,v)+T_v)，每个源都初始化为 (T_s)。 

所有这些转型成本都是正的。 因此，Dijkstra 按照其真实最短路径成本的非递减顺序最终确定顶点。 由于所有源都是最初插入的，因此最短路径可以从最适合该城市的源开始。 因此，最终的 (dist[v]) 正是 (v) 可以完全燃烧的最早时间。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    graph = [[] for _ in range(n)]

    for _ in range(m):
        a, b, c = map(int, input().split())
        a -= 1
        b -= 1
        graph[a].append((b, c))
        graph[b].append((a, c))

    t = list(map(int, input().split()))

    sources = list(map(int, input().split()))

    INF = 10**30
    dist = [INF] * n
    pq = []

    for x in sources:
        x -= 1
        if t[x] < dist[x]:
            dist[x] = t[x]
            heapq.heappush(pq, (t[x], x))

    while pq:
        cur, u = heapq.heappop(pq)

        if cur != dist[u]:
            continue

        for v, w in graph[u]:
            candidate = cur + w + t[v]

            if candidate < dist[v]:
                dist[v] = candidate
                heapq.heappush(pq, (candidate, v))

    sys.stdout.write("\n".join(map(str, dist)))

if __name__ == "__main__":
    solve()
```邻接表代表原始道路网络。 每条道路都向两个方向插入，因为火可以沿着任一方向传播。 

初始化是与普通单源Dijkstra的主要区别。 每个初始源同时进入堆，具有优先级 (T_s)。 如果同一城市在源中出现多次，则重复初始化不会产生有害影响，因为所有出现的值都相同。 

松弛公式是实现的核心部分：```
candidate = cur + w + t[v]
```这里`cur`就是现在的城市完全被烧毁的时候。 然后火就熄灭了`w`过马路的秒数`t[v]`秒烧目的地城市。 

陈旧条目检查```
if cur != dist[u]:
    continue
```是必要的，因为Python的`heapq`不提供减键操作。 当发现更好的距离时，我们会推送另一个条目，而不是修改旧的条目。 旧条目最终会从堆中出来，并且必须被忽略。 

Python 整数具有任意精度，因此不存在溢出问题。 无论如何，最大有用的答案在普通的 64 位整数范围内，但是使用`10**30`因为无穷大使实现变得简单。 

该图最多有 (10^5) 条边，因此邻接表最多存储 (2\cdot10^5) 个有向邻接条目。 堆最多包含执行过程中线性数量的有用或过时的条目，这适合内存限制。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O((N+M)\log N)) | 每次松弛都通过二叉堆进行处理，并且该图有 (O(M)) 个邻接条目 |
 | 空间| (O(N+M)) | 邻接表、距离数组、优先级队列在图大小上都是线性的 |

 对于 (N,M\le 10^5)，该算法使用堆操作执行一次图遍历，而不是最多 (10^5) 次单独的遍历。 (O((N+M)\log N)) 界限适合一秒的限制，并且 (O(N+M)) 内存使用量适合在 256 MB 以内。
