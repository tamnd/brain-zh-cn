 ## 解决方案
 ## 问题理解

 我们给出了几个独立的区间，并且我们必须从每个区间中选择一个值。 在为每个区间选择一个值后，我们将这些值视为向量的大小。 关键问题是我们是否可以为这些向量指定方向，使它们的向量和恰好为零。 

问题背后的几何学将一切都简化为数字的单一条件。 如果一个选定的值与所有其他值的总和相比太大，那么无论我们如何定向方向，最大的向量都无法被其余向量完全抵消。 如果不存在这种不平衡，那么在一维上总是存在有效的方向，因为我们总是可以不断调整方向以在某个点平衡系统。 

每个区间都具有灵活性，但仅限于其范围内。 真正的决策是如何从每个区间中选择一个值，以便所选值的多组能够满足平衡条件。 

这些约束意味着每个测试用例在最坏的情况下需要 O(n) 或 O(n log n) 的解决方案。 任何试图探索区间选择组合的方法，即使是简化的形式，一旦 n 增长超过几十，就会立即变得指数级且无法使用。 

当最大间隔未固定在其最大端点时，就会出现微妙的失败情况。 例如，考虑区间 [5, 10]、[1, 2]、[1, 2]。 幼稚的方法可能会假设选择所有最大值始终是最佳的，但这可能会不必要地夸大最大值并错误地拒绝可行的配置。 正确的推理必须在尊重可行性的情况下考虑向下调整最大区间。 

当多个区间与最大下界相关或当减少最大元素改变哪个区间成为主导时，会出现另一种边缘情况。 通过右值而不是左值固定最大值的粗心实现将在这里失败。 

## 方法

 强力解释将尝试每个间隔一个值的所有选择，并且对于每个选择，检查我们是否可以分配符号以使总和为零。 检查固定选择减少为验证任何元素是否超过总和的一半，这是线性的。 然而，选择的数量是间隔长度的乘积，间隔长度是 n 的指数，这使得除了非常小的输入之外这是不可能的。 

关键的观察是我们实际上不需要枚举选择。 我们只关心是否存在一个选择可以避免“主导元素”超过所有其他元素的总和。 这将问题转化为构建所选值的有效多重集。 

我们确定具有最大下限的区间，因为该区间最难减小。 我们尝试从中确定一个候选值，然后尝试确保所有其他选定的值都可以支持它而不违反平衡条件。 

如果我们从临界区间中选择一个值 x，那么所有其他区间最多贡献其所选界限的值，并且我们希望其他区间的总和至少为 x。 这将问题转化为检查 x 是否可以由其约束下的剩余区间支持。 贪心策略是在不超过 x 的情况下最大化其他区间的贡献，因为任何高于 x 的值都无助于进一步平衡条件。 

这导致了直接构造：选择具有最大下限 l_i 的区间作为锚，将其值设置为 l_i，并且对于每个其他区间选择 min(r_j, l_i)。 这最大化了对支持锚点的贡献，同时保持与间隔边界的一致性。

 ## 算法演练

我们专注于构建可行的选择而不是搜索。 

### 1. 确定关键区间

 我们找到具有最大左端点的区间。 此间隔是最严格的，因为它迫使任何有效的解决方案都可能至少支持该数量级。 

### 2. 暂时固定其选择的值

 我们将此间隔的选定值设置为其下限。 我们不会尝试更大的值，因为增加它只会使平衡变得更加困难。 

### 3. 贪婪地为所有其他区间赋值

 对于每隔一个间隔，我们选择不超过临界值的最大值。 具体来说，我们选择 min(r_j, l_max)。 这确保每个间隔都尽可能地为支持临界值做出贡献，而不会破坏可行性。 

### 4. 通过总和比较检查可行性

 我们计算所有选定值的总和。 如果该总和至少是所选临界值的两倍，则其余值可以抵消它，这意味着零向量配置是可能的。 

如果总和较小，则不存在有效的构造。 

### 为什么它有效

 正确性依赖于将矢量抵消条件转换为单个优势约束。 当且仅当在选择值后没有元素超过所有其他元素的总和时，配置才是可行的。 通过锚定最大的下限区间并最大化该锚点的所有其他贡献，我们为该区间构建了最佳的可能支持环境。 如果连这个最大支持都失败了，任何其他选择都只会进一步减少支持，使可行性变得不可能。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    seg = [tuple(map(int, input().split())) for _ in range(n)]

    # find interval with maximum left endpoint
    i_max = 0
    for i in range(1, n):
        if seg[i][0] > seg[i_max][0]:
            i_max = i

    x = seg[i_max][0]

    total = 0
    for i, (l, r) in enumerate(seg):
        if i == i_max:
            total += x
        else:
            if r < x:
                total += r
            else:
                total += x

    # feasibility condition
    print("YES" if total >= 2 * x else "NO")

if __name__ == "__main__":
    solve()
```该代码首先识别具有最大下限的区间，因为这确定了最难满足的约束。 然后它将其选择的值固定为该下限。 对于每个其他间隔，它会尽可能多地支持该锚点，但永远不会超过它。 

最终检查将总贡献与锚点的两倍进行比较，这对剩余向量是否可以完全平衡它进行编码。 

一个微妙的点是，我们从不单独显式地计算“其他的总和”； 相反，我们将锚点包含在总数中并与 2x 进行比较。 这可以避免差一的错误并保持实现的线性。 

## 工作示例

 ### 示例 1

 考虑间隔：

 [3, 5], [1, 2], [2, 4]

 最大左端点为 3，因此 x = 3。 

| 间隔| 选择值| 贡献 |
 | --- | --- | --- |
 | [3,5]| 3 | 3 |
 | [1,2]| 2 | 2 |
 | [2,4]| 3 | 3 |

 总计 = 8，且 2x = 6，因此条件成立。 

这表明，即使有些区间不能达到3，但它们的最大贡献仍然足以平衡锚点。 

### 示例 2

 考虑间隔：

 [10, 10], [1, 2], [1, 2]

 这里 x = 10。 

| 间隔| 选择值| 贡献 |
 | --- | --- | --- |
 | [10,10]| 10 | 10 10 | 10
 | [1,2]| 2 | 2 |
 | [1,2]| 2 | 2 |

 总计 = 14，且 2x = 20，因此条件失败。 

这演示了一种失效模式，其中一个间隔相对于所有其他间隔来说太大，即使在最大支撑下也是如此。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as sysio

    out = sysio.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    n = int(input())
    seg = [tuple(map(int, input().split())) for _ in range(n)]

    i_max = 0
    for i in range(1, n):
        if seg[i][0] > seg[i_max][0]:
            i_max = i

    x = seg[i_max][0]

    total = 0
    for i, (l, r) in enumerate(seg):
        total += x if (i == i_max and l <= x <= r) else min(r, x)

    print("YES" if total >= 2 * x else "NO")

# minimum case

# tight boundary case
assert run("2\n5 5\n5 5\n") == "YES"

# impossible spread

 ## 边缘情况

 单区间情况是最简单的。 对于输入 [0, 5]，算法选择 x = 0 并立即满足条件，因为没有其他约束。 计算出的总数等于 0，2x 也为零，所以答案是“是”。 

严格约束的等间隔情况，例如 [5,5]、[5,5] 设置 x = 5。两个间隔都贡献 5，总计 10 等于 2x，产生 YES。 这证实了平等处理是正确的，并且不需要严格的不平等。 

像 [10,10]、[1,1] 这样的强烈不平衡情况设置 x = 10。第二个区间仅贡献 1，使得总数为 11，远低于 20，因此算法正确地拒绝它。 这表明即使最大化较小的间隔，它们也无法补偿过大的锚定间隔。
