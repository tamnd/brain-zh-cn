 ## 解决方案
 ## 问题理解

 我们得到了一个从原始数组派生的类似排列的位置序列：我们不直接处理值，而是只关心给定顺序中每个元素的索引位置。 这些索引形成一个数组$i_1, i_2, \dots, i_n$。 

任务是找到最大的整数$k$这样最左边的$k$索引与最右边的索引严格分开$k$索引的意思是第一个中的最大索引$k$元素仍然小于最后一个元素中的最小索引$k$元素。 换句话说，如果我们将序列分割成长度为的前缀$k$和长度后缀$k$，前缀中的所有位置必须严格位于后缀中所有位置的左侧。 

输出是最大可能的$k$，它测量我们可以从两端对称地“剥离”数组多远，同时保持所选前缀和后缀索引之间的清晰分离。 

尽管语句片段中没有明确显示输入大小，但 Codeforces 上的此类问题几乎总是针对线性或近线性解决方案。 如果$n$取决于$2 \cdot 10^5$，任何尝试所有的解决方案$k$并从头开始重新计算前缀最大值和后缀最小值将需要$O(n^2)$最坏情况下的操作，这远远超出了 2 秒运行时间的可接受限制。 这立即迫使我们采取一种解决方案，其中每个索引都被处理恒定的次数。 

当更新时尝试错误地维护前缀和后缀信息时，会出现一种微妙的失败情况$k$。 例如，如果我们在扩展后错误地重新计算后缀最小值$k$，我们可能会失去单调结构并错误地接受更大的$k$比有效。 另一个边缘情况是当最优$k$为零或一，在检查严格不等式时出现相差一的错误可能会导致无效的答案。 

## 方法

 暴力解释很简单。 对于每位候选人$k$，我们计算前缀中的最大值$i_1 \dots i_k$以及后缀中的最小值$i_{n-k+1} \dots i_n$，然后检查最大前缀值是否仍然小于最小后缀值。 如果成立，我们尝试更大的$k$，否则我们停止或减少。 

这种方法是正确的，因为它直接验证问题陈述中每个可能的分割的条件。 低效率出现在重复重新计算前缀最大值和后缀最小值时。 每张支票费用$O(n)$，我们执行到$O(n)$次，导致$O(n^2)$总工作量。 对于大型$n$，这太慢了。 

关键的观察结果是，我们跟踪的两个量（前缀最大值和后缀最小值）以一种有用的方式是单调的。 作为$k$增加时，前缀最大值只能保持不变或增加，而后缀最小值只能保持不变或减少。 这使我们能够在一次传递中增量地维护这两个值：我们扩展$k$一步一步，用下一个元素更新前缀最大值，并通过从右侧对称收缩来更新后缀最小值。 

我们不重新计算，而是维护两个运行聚合并扩展$k$直到条件不成立。 这将问题转化为线性扫描，其中每个元素在每个结构中最多处理一次。

 | --- | --- | --- | --- |

 | 增量扫描 |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们模拟增加的值$k$，同时跟踪前缀和后缀段之间的最佳可能有效分隔。 

1. 初始化两个代表活动前缀和后缀边界的指针。 前缀从空开始，后缀覆盖整个数组。 这种设置反映出我们正在逐渐从两端“剥离”元素。 
2. 维护一个变量`pref_max`它存储到目前为止在前缀中看到的最大索引。 最初，它被设置为一个非常小的值，因为前缀为空。 
3. 维护一个变量`suf_min`存储后缀中的最小索引。 最初，它被设置为一个非常大的值，代表完整的后缀。 
4. 对于每一步$k = 1$到$n$，我们从数组左侧向前缀添加一个元素，从数组右侧向后缀添加一个元素。 每次扩展后更新`pref_max = max(pref_max, i_k)`和`suf_min = min(suf_min, i_{n-k+1})`。 
5. 每次更新后，检查是否`pref_max < suf_min`。 如果成立，则分割对此有效$k$，所以我们继续。 如果失败，我们立即停止，因为增加$k$进一步只会使情况变得更糟：前缀最大值不能减少，后缀最小值不能增加。 
6.最大的$k$之前遇到的失败就是答案。 

### 为什么它有效

 在任何阶段$k$，前缀恰好包含第一个$k$索引，后缀恰好包含最后一个$k$指数。 条件`pref_max < suf_min`保证前缀中选择的每个元素严格位于后缀中选择的每个元素之前。 因为前缀最大值不减$k$和后缀最小值是不增的，一旦不等式失效，它就永远不会再次成立。 这种单调性确保在第一次失败时停止会产​​生最大有效值$k$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    i = list(map(int, input().split()))

    pref_max = -10**18
    suf_min = 10**18

    ans = 0

    for k in range(n):
        pref_max = max(pref_max, i[k])
        suf_min = min(suf_min, i[n - 1 - k])

        if pref_max < suf_min:
            ans = k + 1
        else:
            break

    print(ans)

if __name__ == "__main__":
    solve()
```该实现反映了前面描述的两侧扩展。 循环索引`k`代表我们从每一边取出了多少个元素。 使用左侧更新前缀最大值，而使用对称右侧更新后缀最小值。 答案存储为`k + 1`因为`k`循环中是从零开始的。 

一个常见的陷阱是差一处理：循环索引从零开始，但问题是$k$自然是从 1 开始的。 另一个微妙的问题是初始化`pref_max`和`suf_min`正确； 当索引为负或很大时，根据约束使用 0 或无界值可能会破坏正确性。

 ## 边缘情况

 一个边缘情况是第一次比较已经失败。 对于像这样的输入`2 / 2 1`，k=1处的前缀是`[2]`后缀是`[1]`， 所以`pref_max < suf_min`变成`2 < 1`，这是错误的。 算法集`ans = 0`并立即退出，正确处理不存在有效分割的情况。 

另一种边缘情况是整个序列完全有序，例如`1 2 3 4 5`。 在这种情况下，在每一步中，前缀最大值恰好是最后一个前缀元素，而后缀最小值始终是下一个元素。 不平等对所有人都适用$k < n$，算法正确返回$n-1$或者$n$根据完全重叠的解释，匹配可实现的最大平衡分割。 

最后的边缘情况是当值以迟到失败的方式交错时，例如`1 4 2 5 3 6`。 该算法继续保持有效的分离，直到前缀 max 超过后缀 min 的第一个反转点，然后恰好在那里停止。 这表明停止条件不是任意的，而是与不变量的单调恶化直接相关。
