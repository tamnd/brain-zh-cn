 ## 解决方案
 ## 问题理解

 我们得到了一系列正整数，代表排成一行的参与者的强度。 任务是选择一个分割位置，将数组分为左前缀和右后缀。 分组得分定义为左侧总力量与右侧总力量的乘积。 目标是找到最大化该乘积的分割。 

换句话说，如果我们将索引 k 之前的前缀和表示为$S_k$，则分割 k 处的分数为$S_k \cdot (S_N - S_k)$。 我们想要从 1 到 N-1 的所有有效 k 的最大值。 N 等于 1 时的特殊情况是微不足道的，因为一侧是空的并且乘积为零。 

约束允许最多$10^5$元素，每个元素最多$10^4$。 这立即排除了任何结合重新计算总和的分割头寸的二次方法。 尝试每次分割并从头开始重新计算双方的解决方案将起到以下作用：$O(N^2)$添加，对于时间限制来说太慢了。 

常见的边缘情况是所有元素都相等。 例如，如果数组为 [1, 1, 1, 1]，则最佳分割位于中间，生成 2 和 2，从而得到 4。对前缀和管理不善的幼稚方法可能会错误地重新计算部分范围或错过最佳平衡分割。 

另一个微妙的情况是 N = 1。对于输入 [x]，任何分割在通常意义上都是无效的，但问题将答案定义为 0。总是从 1 到 N 计算 k 的粗心实现可能会尝试错误地计算两边或访问空后缀而不显式处理它。 

## 方法

 蛮力的想法很简单。 对于每个可能的分割位置 k，计算从 1 到 k 的元素之和以及从 k+1 到 N 的元素之和，然后将它们相乘。 每次求和计算都可以通过扫描数组来完成，因此每次拆分都会花费$O(N)$。 由于有$O(N)$分裂，总复杂度变成$O(N^2)$。 和$N = 10^5$，这将涉及到$10^{10}$的操作，远远超出了可行的限度。 

关键的观察是重复重新计算总和是浪费的。 一旦我们知道了数组的总和，分割的右侧总和就可以在常数时间内从左侧总和导出。 如果我们在迭代数组时保持运行的前缀和，则每次分割评估都会变成$O(1)$。 这减少了从重新计算范围到维护单个累积状态的问题。 

因此，我们不是重新计算总和，而是计算一次总和，然后扫描数组，更新前缀总和。 在每个位置，正确的总和就是总和减去前缀。 我们计算乘积并跟踪最大值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N^2) | O(N^2) | O(1) | O(1) | 太慢了|
 | 前缀和扫描| O(N) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算数组中所有元素的总和。 这表示在选择任何分割之前双方组合的总和。 
2. 初始化变量`prefix`为零。 当我们将分割点从左向右移动时，这将存储左侧的总和。 
3. 初始化变量`best`为零。 这存储了迄今为止找到的最大产品。 
4. 从第一个元素到倒数第二个元素迭代数组。 我们在最后一个元素之前停止，因为右侧必须非空才能进行有意义的分割。 
5. 在每个索引 i 处，将当前元素添加到`prefix`。 这通过包括当前参与者来扩展左组。 
6. 计算右侧总和：`total - prefix`。 这是可行的，因为每个元素要么在前缀中，要么在后缀中，因此相减可以得到精确的剩余总和。 
7. 计算分数`prefix * (total - prefix)`并更新`best`如果该值大于当前最大值。 

完成迭代后，`best`保持最大可能的分数。 

正确性依赖于这样一个事实：每个有效的分割恰好对应于一个前缀和值。 通过迭代所有前缀，我们枚举所有可能的分区，并且对于每个分区，我们计算准确的分数，没有近似或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 1:
        print(0)
        return

    total = sum(a)
    prefix = 0
    best = 0

    for i in range(n - 1):
        prefix += a[i]
        right = total - prefix
        best = max(best, prefix * right)

    print(best)

if __name__ == "__main__":
    solve()
```该解决方案首先显式处理单元素情况，因为不存在有效的分割。 总和计算一次并在整个扫描过程中重复使用。 循环停止于`n-1`确保后缀非空。 

一个微妙的细节是更新的顺序：我们将元素添加到`prefix`在计算乘积之前，它将索引 i 与包含 a[i] 后的分割对齐。 混合此顺序会改变分割并产生不正确的结果。

 ## 边缘情况

 对于输入`1 7`，没有有效的分割。 该算法检测到`n == 1`并立即返回0而不进入循环。 这可以避免涉及空后缀的任何错误计算。 

为了`10 10`，总和为 20。当 i = 0 时，前缀变为 10，后缀也为 10，产生 100。由于只有一个分割，算法正确地评估了一个候选者。 

为了`[1, 1, 1, 1, 1]`，总数为 5。前缀进化产生乘积 1×4、2×3、3×2、4×1。 中间分割的最大值为 6，并且扫描对每个可能的分割精确地评估一次，确保不会丢失任何情况。 

为了`[5, 4, 3, 2, 1, 0]`，零的存在不影响正确性。 最佳分割发生在较小的后缀占主导地位之前。 前缀-后缀分解仍然成立，因为总和中包含零，并且减法公式对于每个位置仍然有效。
