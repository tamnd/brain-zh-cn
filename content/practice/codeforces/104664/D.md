 ## 解决方案
 ## 问题理解

 我们有一个正方形棋盘，大小为$N \times N$，其中正方形由整数坐标索引。 单个骑士从一个方格开始，我们想知道到达目标方格所需的合法骑士移动的最少次数。 如果由于棋盘边界或奇偶校验限制，骑士永远无法到达目标，我们输出$-1$。 

棋盘是空的，所以没有障碍物。 唯一的结构是骑士的移动规则，它定义了每个方格最多八个可能的转换的固定集合。 这将问题转化为隐式图上的最短路径问题：每个单元格都是一个节点，每个骑士的移动都是一个未加权的边。 

限制因素$N < 800$至多暗示$640{,}000$节点。 每个节点最多有 8 个传出边，因此完整的探索涉及数百万个转换。 如果仔细实现的话，这完全在 Python 的 BFS 预算之内。 

有一些影响正确性的重要边缘情况：

 一种情况是起始位置和结束位置相同。 例如：```
N = 1
start = (0, 0)
end = (0, 0)
```正确答案是$0$。 粗心的 BFS 实现总是首先将邻居入队，并且仅在出队可能仍返回时才检查终止$1$如果它过早地增加距离。 

另一种情况是棋盘太小，无法进行任何马的移动。 例如：```
N = 2
start = (0, 0)
end = (1, 1)
```骑士在任何地方都没有合法的移动$2 \times 2$板，因此大多数单元在实践中都是隔离的。 正确答案是$-1$除非开始等于结束。 任何假设连通性或忽略边界的解决方案都将错误地返回有限数。 

最后，奇偶校验在有限的板上仍然发挥着作用。 即使理论上可以在无限棋盘上到达某个位置，但边界截断也可能使其无法到达。 这意味着仅基于奇偶校验或曼哈顿距离的启发式公式是不安全的； 我们必须明确地搜索。 

## 方法

 一种直接的方法是将每个板单元视为图顶点并运行最短路径搜索。 从每个位置，我们生成最多八个骑士动作，过滤掉那些落在棋盘之外的动作，并继续探索，直到到达目标。 因为所有的移动都有相同的成本，广度优先搜索保证了我们第一次到达目标的时间是最优的。 

这是正确的，但如果做得不好或不跟踪重复的状态，就会变得昂贵。 如果没有被访问的结构，同一个单元格会以指数方式被重新访问多次，因为骑士的移动自然循环。 在最坏的情况下，这会退化为探索无限展开的树，这是不可行的。 

关键的观察结果是该图是未加权的并且具有统一的边缘成本。 这使得 BFS 最优。 第二个观察结果是状态空间足够小，从一开始单个 BFS 就足够了。 我们不需要像 A* 这样的双向搜索或启发式方法； 网格密集但有界。 

该解决方案最多减少到单个 BFS$N^2$具有恒定分支因子的状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（DFS/反复探索）| 指数| O(N²) 或更差 | 太慢了|
 | BFS最短路径| O(N²) | O(N²) | 已接受 |

 ## 算法演练

 1. 解释每个板单元$(x, y)$作为图中的节点。 
2. 定义八个骑士动作：$(\pm 1, \pm 2)$和$(\pm 2, \pm 1)$。 
3. 如果 start 等于 target，则立即返回 0，因为不需要移动。 
4. 初始化距离网格（或访问过的数组）$-1$，表示未访问过。 
5. 将起始单元距离设置为 0 并将其推入队列。 
6. 当队列不为空时，弹出最前面的单元格$(x, y)$。 
7. 对于八个可能的移动中的每一个，计算下一个单元格$(nx, ny)$。 
8. 如果$(nx, ny)$在板外或已访问过，请跳过。 
9. 否则，将其距离设置为$dist[x][y] + 1$并将其推入队列。 
10. 如果在此过程中到达目标单元格，则立即返回其距离。 
11.如果BFS完成后没有达到目标，则返回$-1$。 

这样做的原因是 BFS 从起点开始按照距离递增的顺序扩展节点。 每个单元都被分配了到达它所需的最小步数，因为第一次发现它对应于未加权图中的最短可能路径。 访问过的标记确保每个单元格都被处理一次，从而防止循环距离膨胀或导致无限循环。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    N = int(input().strip())
    x1, y1 = map(int, input().split())
    x2, y2 = map(int, input().split())

    if (x1, y1) == (x2, y2):
        print(0)
        return

    moves = [(1, 2), (2, 1), (2, -1), (1, -2),
             (-1, -2), (-2, -1), (-2, 1), (-1, 2)]

    dist = [[-1] * N for _ in range(N)]
    q = deque()
    q.append((x1, y1))
    dist[x1][y1] = 0

    while q:
        x, y = q.popleft()

        for dx, dy in moves:
            nx, ny = x + dx, y + dy

            if 0 <= nx < N and 0 <= ny < N and dist[nx][ny] == -1:
                dist[nx][ny] = dist[x][y] + 1
                if (nx, ny) == (x2, y2):
                    print(dist[nx][ny])
                    return
                q.append((nx, ny))

    print(-1)

if __name__ == "__main__":
    solve()
```实现直接遵循BFS。 距离数组兼作访问标记，从而无需单独的布尔数组。 达到目标后尽早退出可以避免不必要时探索整个棋盘。 

一个微妙的细节是我们在访问距离数组之前检查边界。 另一个是我们只为每个单元分配一次距离； 这就是保持最短路径正确性的原因。 

## 工作示例

 ### 示例 1

 输入：```
N = 1
start = (0, 0)
end = (0, 0)
```这种情况在 BFS 开始之前处理。 

| 步骤| 队列| 分布更新 | 行动|
 | ---| ---| ---| ---|
 | 初始化| （跳过空 BFS）| 无 | 开始==目标|

 输出立即为0。这证实了提前终止规则的正确性。 

### 示例 2

 输入：```
N = 4
start = (1, 2)
end = (2, 2)
```我们跟踪 BFS 层。 

| 步骤| 队列| 新访问 | 原因 |
 | ---| ---| ---| ---|
 | 初始化| (1,2) | (1,2)=0 | (1,2)=0 开始 |
 | 流行 (1,2) | 邻居 | (0,0),(0,4 无效),... | 展开骑士动作|
 | 下一层| 多个| 一些有效的单元格| BFS 前沿不断增长 |
 | 达到目标| 发现 | (2,2)=3 | (2,2)=3 | 第一次到达|

 关键的观察是，即使有多个路径到达一个小区，BFS 也能保证首次到达的概率最小。 这个例子展示了距离如何逐层累积，而不是通过启发式跳跃。

 ## 边缘情况

 一种重要的边缘情况是板太小而无法移动。 对于输入：```
N = 2
start = (0, 0)
end = (1, 1)
```BFS 开始于$(0,0)$。 骑士的八个动作全部立即出界。 处理完起始节点后队列变空。 由于从未达到目标，算法返回$-1$，匹配正确的结果。 

另一种情况是相同的开始和结束：```
N = 5
start = (3, 3)
end = (3, 3)
```该算法在 BFS 之前检查这一点并直接返回 0，从而防止不必要的探索。 

第三种情况是只有经过几次扩展才能到达目标：```
N = 4
start = (0, 0)
end = (3, 3)
```BFS逐层扩展。 即使有多条路径到达中间单元格，第一次$(3,3)$出队或被发现对应于最小移动次数。 这可以防止通过较长路线重新访问单元格的路径计数过多。
