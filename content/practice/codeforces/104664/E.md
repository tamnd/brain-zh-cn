 ## 解决方案
 ## 问题理解

 给定偶数个数组，每个数组都是从 1 到某个公共长度的数字的排列$n$。 任何数组上允许的关键操作是循环旋转，其中最后一个元素移到前面。 如果经过一定次数的此类旋转后，排列完全变为“已解决”$[1,2,\dots,n]$。 

一个关键的变化是在执行任何旋转之前将阵列配对。 每个数组必须与另一个数组精确配对，并且当我们旋转一对数组中的一个数组时，相同的旋转将应用于其配对。 对于一对，我们选择单个轮换策略并将其同步应用于两者。 

仅当该对中的两个数组都可以使用相同的旋转次数旋转为排序的恒等排列时，该对才能成功贡献。 目标是选择配对，以便在对每对应用最佳旋转后，对尽可能多的单独数组进行排序。 

输入尺寸很小，最多有$10^3$排列，每个长度最多$10^3$。 这立即排除了比粗略更糟糕的情况$O(N \cdot n)$或者$O(N \cdot n \log n)$。 对所有配对采用三次方法会太慢，因为配对的数量会呈阶乘增长。 

当排列不是循环移位时，会出现微妙的边缘情况$[1..n]$。 例如，$[2,1,3,4]$根本无法旋转为排序顺序。 即使旋转改变了数组，但没有旋转产生排序序列，因此这种排列基本上是“无法解决的”，并且永远不应该被视为有贡献。 

另一种边缘情况是当多个排列是有效的循环移位但对应于不同的旋转偏移时。 配对不匹配的班次会破坏两者，尽管每个都可以单独解决。 

## 方法

 蛮力视角首先想象我们尝试每一种可能的配对$N$数组。 对于每个配对，我们尝试为每个配对选择一个旋转值，以最大化排序的元素数量。 即使对于固定配对，检查可行性也涉及比较每对内的轮换要求，并且配对的数量是天文数字，大约是$(N-1)!!$。 即使对于$N=1000$。 

关键的简化来自于观察到只有当它是循环移位时才能解决排列$[1..n]$。 每个有效排列都有一个定义的旋转偏移量：值 1 的位置准确地确定需要旋转多少次才能将其与前面对齐，并且如果结构的其余部分与递增顺序匹配，则该偏移量适用于整个数组。 

一旦每个排列都映射到“无效”或旋转类$r$，问题简化为对相同的轮换类进行分组。 同一组内$r$，我们可以任意配对排列，并且每一对恰好贡献两个已求解的数组。 组间的任何不匹配或涉及无效排列都不会产生任何影响。 

因此，任务变成计算旋转值的频率，并对每个桶内可以形成多少对进行求和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力配对 | 指数| O(N) | 太慢了|
 | 按旋转类别划分的频率 | O(N·n) | O(N) | 已接受 |

 ## 算法演练

 1. 对于每个排列，确定值 1 出现的位置。 该位置决定了使数组从 1 开始的唯一可能的旋转。 
2. 验证排列是否是有效的循环移位$[1..n]$。 从1的位置开始，检查循环遍历数组是否产生$1,2,3,\dots,n$。 如果不是，则完全放弃此排列。 
3. 对于有效的排列，计算旋转签名$r$，它是 1 的索引。这唯一标识对其进行排序所需的旋转。 
4. 维护一个频率数组或字典，计算每个旋转签名中有多少排列。 
5. 对于每个轮换签名$r$，计算可以形成多少对，即$\lfloor \text{cnt}[r] / 2 \rfloor$。 每对都贡献 2 个已解出的密码。 
6. 将所有签名相加得到最终答案。 

这样做的原因是，两个排列可以一起求解的唯一方法是它们在旋转之前已经相同。 除了匹配相同的旋转要求之外，配对约束不会引入新的灵活性，因为一对中的两个数组必须共享相同的旋转值才能同时排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arrs = []
    for _ in range(n):
        parts = list(map(int, input().split()))
        arrs.append(parts[1:])

    freq = {}

    for p in arrs:
        m = len(p)

        # find position of 1
        pos1 = -1
        for i in range(m):
            if p[i] == 1:
                pos1 = i
                break

        # check cyclic shift validity
        ok = True
        for i in range(m):
            if p[(pos1 + i) % m] != i + 1:
                ok = False
                break

        if not ok:
            continue

        freq[pos1] = freq.get(pos1, 0) + 1

    ans = 0
    for c in freq.values():
        ans += (c // 2) * 2

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先解析所有排列并独立处理每个排列。 对 1 位置的扫描是线性的，并且验证循环确保排列确实是身份的循环移位，而不是仅在有效位置中具有 1。 

频率图存储旋转签名。 最终的累积将每个组转换为尽可能多的完整对，每个对贡献两个已求解的数组。 

一个微妙的实现细节是，无效排列被完全忽略，而不是计入任何存储桶中。 将它们与有效的配对永远不会有好处，因为它们无法在任何轮换下进行排序。

 ## 边缘情况

 当排列在“合理”位置上有 1 但实际上不是恒等式的循环移位时，就会出现微妙的故障模式。 例如，$[1,3,2,4]$索引 0 处有 1，但没有旋转产生排序序列。 该算法显式验证完整结构，而不是单独信任 1 的位置，确保排除此类情况。 

另一种边缘情况是频率类别为奇数时。 例如，三个相同的有效旋转不能全部一起求解。 该算法仅正确地形成一对，留下一个无法有效配对的未使用排列。 

最后的边缘情况是所有排列都无效。 在这种情况下，每个频率桶都是空的，并且答案正确地变为零，因为没有一对可以产生完全可解的配置。
