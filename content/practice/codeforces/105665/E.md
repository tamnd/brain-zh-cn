 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，然后我们重复回答对子数组的查询。 对于每个查询，我们都会查看一个连续的段，并尝试测量使用非常具体的操作转换该段所需的一定“努力”。 

该操作不会直接删除元素。 相反，我们选择当前序列中的任意两个值，删除这两个值，然后插入它们的乘积。 这会将多重集大小更改为 1，并且还会混合元素之间的质因数。 执行几次此类操作后，我们希望每个剩余元素都满足严格条件：每个数字必须至少有两个不同的素因数。 

对于给定的子数组，答案是达到这种状态所需的最少操作数，否则我们报告这是不可能的。 

关键的隐藏结构是该操作仅合并因式分解。 它永远不会引入新的素数因子，也不能删除素数，除非将它们配对成一个乘积。 这立即表明问题不在于值本身，而在于它们的质因数分解如何相互作用。 

约束足够大，我们无法从头开始重新计算每个查询的任何内容。 对于多达 200,000 个元素和查询，每个查询因式分解或贪婪模拟将远远超出时间限制。 即使每个查询的线性扫描也会导致二次行为。 

当段已经很小或仅包含特殊值（如 1 或素数）时，会出现微妙的边缘情况。 例如，如果该段是`[1]`，没有办法让它有效，因为 1 没有质因数，并且在单元素状态下不可能将其与任何值相乘。 类似地，单个素数的一段`[7]`也是不可能的，因为如果没有另一个元素相结合，我们就无法创建第二个不同的质因数。 

另一个棘手的情况是当有许多合数已经满足条件时。 一个幼稚的解决方案可能仍然执行不必要的操作或错误地假设可行性仅取决于“坏”数字的计数，但坏元素之间的相互作用很重要：两个坏数字可以组合起来修复两者，但前提是它们的因子结构配合。 

## 方法

 暴力策略将模拟每个查询的过程。 对于给定的子数组，我们重复扫描两个元素，合并它们，并检查所有剩余的数字是否“好”。 每次合并都需要重新计算因子信息，并且每个查询最多可以进行 O(n) 次合并。 这会导致跨查询在最坏情况下出现 O(n³) 行为，当 n 和 q 很大时这是完全不可行的。 

关键的见解是停止将序列视为不断变化的值，而是根据每个元素是否已经有效或仍然“有缺陷”对其进行分类。 如果一个数的不同质因数少于两个，则该数是有缺陷的。 唯一有意义的工作是修复这些有缺陷的元素，因为已经好的数字在乘法下永远不会变坏。 

每个操作都会合并两个元素，因此在结构层面上，每个操作最多可以将两个有缺陷的项目修复为一个新项目。 这意味着答案几乎完全由查询范围中存在多少缺陷元素来控制，除非涉及极小或结构受限的值的特殊情况，其中合并无法产生有效结果。 

一旦以这种方式重新构建问题，任务就变成在许多范围查询中有效地维护缺陷元素的计数。 这正是前缀和或 Fenwick 树可以支持的功能，在预处理后将每个查询减少到 O(1) 或 O(log n)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n3) | O(n) | 太慢了 |
 | 因子分类+前缀和| O(n log n + q) | O(n log n + q) | O(n) | 已接受 |

 ## 算法演练

 1. 预先计算每个数字是否“好”，即它至少有两个不同的质因数。 这是使用最小素因子筛并检查每个值的不同素数来完成的。 此步骤将每个值转换为布尔分类而不是原始整数。 
2. 将数组转换为二进制数组，其中 1 表示有缺陷（坏），0 表示已经良好。 这是查询所需的唯一信息，因为好的元素不需要任何操作。 
3. 在有缺陷的标记上建立前缀和。 这使我们能够在恒定时间内计算任何子数组中存在多少坏元素。 
4. 对于每个查询，计算段中缺陷元素的数量。 将此值称为 b。 
5.如果b为0，则不需要任何操作，因为一切都已经很好了。 
6. 如果b是1，则答案是不可能的，因为一个有缺陷的元件不能与任何东西配对，并且它本身不能被修复。 
7. 如果 b ≥ 2，则答案为 b − 1。每次操作都通过有效地将两个改进元素合并为一个改进元素来减少缺陷项的数量，直到最多保留一个，并且我们需要消除所有缺陷。 

### 为什么它有效

 关键的不变量是，当两个选定的元素都有缺陷时，每个操作都会将缺陷元素的数量减少恰好 1，并且永远不会增加缺陷元素的数量。 在操作中选择任何好的元素都没有好处，因为它不会减少缺陷数量，只会浪费合并机会。 

因此，该过程的行为就像重复配对有缺陷的元素，直到最多剩下一个。 如果至少存在两个，我们总是可以将它们配对； 如果只有一个存在，它将被永久卡住。 因此，答案完全取决于计数是 0、1 还是至少 2。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_spf(mx):
    spf = list(range(mx + 1))
    for i in range(2, int(mx ** 0.5) + 1):
        if spf[i] == i:
            step = i
            start = i * i
            for j in range(start, mx + 1, step):
                if spf[j] == j:
                    spf[j] = i
    return spf

def is_good(x, spf):
    cnt = 0
    last = 0
    while x > 1:
        p = spf[x]
        if p != last:
            cnt += 1
            last = p
        while x % p == 0:
            x //= p
        if cnt >= 2:
            return True
    return False

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    mx = max(a)
    spf = build_spf(mx)

    bad = [0] * (n + 1)
    for i, v in enumerate(a, 1):
        bad[i] = 1 if not is_good(v, spf) else 0

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + bad[i]

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        b = pref[r] - pref[l - 1]
        if b <= 1:
            out.append("-1")
        else:
            out.append(str(b - 1))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```筛子建立最小的质因数，以便每个数字都可以快速分解。 一旦找到两个不同的素数，分类函数就会提前停止，因为我们只关心一个数字是否符合“好”的条件。 

前缀和将每个查询压缩为简单的减法，这是解决方案可以扩展到完整输入限制的唯一方法。 

## 工作示例

 例如，考虑一个数组，其中有缺陷的元素散布在好的元素中`[2, 8, 3, 5, 1, 9, 42, 3]`。 假设查询选择一个仅包含少量有缺陷值的段。 

对于一个段`[2, 8, 3]`，我们对每个数字进行分类。 2 不好，8 不好，3 不好，所以 b = 3。 

| 步骤| 细分 | 错误计数 (b) | 行动| 结果 |
 | ---| ---| ---| ---| ---|
 | 1 | [2,8,3]| 3 | 计算查询| 3 − 1 = 2 |

 这个痕迹表明我们从不模拟操作； 我们只计算结构性缺陷。 

现在考虑一个已经包含大部分好数字的段，例如`[42, 9, 8]`。 这里 42 和 9 是好的，只有 8 是坏的，所以 b = 1。 

| 步骤| 细分 | 错误计数 (b) | 行动| 结果 |
 | ---| ---| ---| ---| ---|
 | 1 | [42,9,8]| 1 | 不可能的情况| -1 |

 这说明了为什么单个有缺陷的元件无法单独修复。

 ## 边缘情况

 包含素数的单元素查询，例如`[7]`结果计数错误为1，因此算法直接输出-1。 前缀和确保在没有特殊大小写的情况下检测到这一点。 

像这样的一段`[6, 10]`如果两个数字都已经很好，则产生 b = 0，因此答案为 0。这证实没有引入不必要的操作。 

例如，一长段素数`[2, 3, 5, 7, 11]`，产生 b = 5，所以答案是 4。算法的每一步都隐含地假设我们可以任意配对有缺陷的元素，这是成立的，因为每次合并都会将缺陷计数减少 1 并且永远不会破坏已经有效的结构。
