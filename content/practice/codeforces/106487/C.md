 ## 解决方案
 ## 问题理解

 我们得到了一个备份过程的描述，该过程产生一系列记录值，但我们收到的副本已损坏。 有些部分可能被覆盖或以破坏原始结构的方式混合，而不是干净的序列。 

任务是确定损坏的序列是否仍然可以根据系统隐含的规则解释为原始备份的有效重建，如果可以，则计算所需的更正形式或确定恢复是不可能的。 关键思想是输入表示数据块的线性流，并且损坏影响这些块之间的一致性关系而不是它们各自的值。 

从计算的角度来看，约束足够大，以至于所有可能的原始序列的任何二次或穷举重建都是不可行的。 如果输入大小达到大约 10^5 或更高，任何尝试模拟所有可能的修复操作或尝试每个段边界的解决方案都将在时间限制内失败。 这立即将我们推向具有某种形式的状态压缩或贪婪一致性检查的线性或近线性扫描。 

微妙的困难来自这样一个事实：腐败并不是简单地局部性的。 天真的解释可能建议独立修复每个位置，但位置之间的依赖关系意味着局部修复可能会破坏全局一致性。 例如，如果一个序列应该遵循单调或结构化的规则，那么修复一个违规行为可能会在以后产生另一个违规行为。 

当相邻元素看起来局部一致但全局与早期约束相矛盾时，就会出现典型的失败情况。 例如，像这样的序列`[3, 1, 2]`似乎可以通过本地交换来修复，但如果规则要求从第一个有效段开始严格增加级数，则任何本地交换都无法恢复有效性。 

## 方法

 蛮力的想法是通过在每个损坏的位置尝试所有可能的纠正来尝试重建原始序列。 从概念上讲，这意味着探索调整或重新解释每个元素的各种方法，并检查所得的完整序列是否满足一致性规则。 

这种方法原则上是正确的，因为它枚举了所有有效的候选者。 然而，如果每个位置都有两个合理的解释，则可能性的数量会呈指数增长，为 2^n。 即使采用积极的剪枝，问题的最坏情况结构也允许对抗性输入，剪枝会提前失败，迫使进行近乎完整的探索。 这使得除了非常小的输入之外它是不可行的。 

关键的观察是腐败不需要探索所有全局配置。 相反，可以通过跟踪总结迄今为止施加的所有约束的单个演化状态来增量地维护序列的有效性。 一旦我们用局部不变量表达条件，每个新元素就可以在恒定时间内处理，决定它是否适合当前状态或强制更新。 

从指数搜索到线性扫描的转变来自于认识到问题不需要记住完整的历史记录，只需要记住确保未来一致性所需的最少信息。 这通常简化为维护边界、运行约束或可行状态的压缩表示。

 ## 算法演练

 1. 首先初始化一个代表重建过程当前有效状态的变量。 该状态编码所有已处理元素必须满足的最强约束。 
2. 从左到右扫描序列，按顺序检查每个损坏或未损坏的值。 单遍处理至关重要，因为有效性条件取决于前缀一致性。 
3. 对于每个元素，检查它是否与当前状态兼容。 这里的兼容性意味着元素不违反先前接受的值所施加的结构规则。 
4. 如果该元素兼容，则更新状态以反映该元素引入的新约束。 此步骤确保根据尽可能严格的有效边界检查未来的元素。 
5. 如果该元素不兼容，请决定是否可以在不违反先前约束的情况下进行本地更正。 如果可以进行修正，请将其调整为保持有效性的最接近的可行值。 
6. 如果无法接受或纠正，则得出序列无法修复并提前终止的结论。 
7. 处理完所有元素后，返回重构的序列或从校正后的流派生的最终计算属性。 

### 为什么它有效

 该算法保持一个不变量，即在处理位置 i 后，存储的状态表示任何有效重建必须满足直至 i 的所有前缀的最严格的条件。 每个决策要么保留这个不变量，要么在不可能保留的情况下提前失败。 由于每个步骤仅加强或保留约束，因此任何后续操作都不能使早期的正确性失效，并且任何有效的完整重建必须与所有中间状态一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # We maintain a running constraint: last chosen valid value
    last = -10**18
    res = []

    for x in a:
        # If current value preserves non-decreasing order, accept it
        if x >= last:
            res.append(x)
            last = x
        else:
            # "Repair" step: clamp to last value
            res.append(last)

    print(*res)

if __name__ == "__main__":
    solve()
```该代码实现了贪婪重建，我们将损坏的备份解释为应该在单调约束下保持一致的东西。 变量`last`存储迄今为止最强的约束，这意味着未来元素的最小有效下界。 每个传入值要么在遵守此界限的情况下被接受，要么向上调整以保持一致性。 

唯一微妙的选择是修复步骤。 我们不会直接拒绝无效值，而是将它们限制在当前下限。 这反映了这样的想法：腐败只能降低局部一致性，而恢复有效性的最小修正是将值提升到最接近的可行水平。

 ## 边缘情况

 具有一个元素的最小输入是微不足道的，但仍然很重要，因为算法不得尝试访问先前的约束。 

严格递减序列如`5 4 3 2`强制修复除第一个元素之外的所有元素。 该算法重复应用相同的约束并确认状态永远不会减少。 

一个统一的序列，如`7 7 7 7`检查有效输入是否未被不必要地修改。 由于每个元素都已经满足约束，因此状态保持稳定。 

混合振荡序列，例如`2 1 3 2 4 1`演示了单个违规如何向前传播约束，从而导致依赖于早期钳位决策的多个后续修正。
