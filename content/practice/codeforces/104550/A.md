 ## 解决方案
 ## 问题理解

 我们得到了一系列以固定时间间隔进行的观察，其中每个值代表当时盘子上有多少蘑菇。 观察期间，可任意添加蘑菇，也可食用。 

任务是重建凯琳在对她的饮食行为的两种不同解释下必须吃掉的蘑菇的最小总数。 

在第一种解释中，进食的时间和速度不受限制。 在每对连续观察之间，蘑菇数量的任何减少都必须由进食来解释。 如果计数增加，我们假设添加了蘑菇，因此不需要吃东西来解释这种变化。 

在第二种解释中，从第一次观察开始，只要有蘑菇，凯林就会以恒定的速度进食。 这意味着我们必须找到一个单一的进食率，这样所有观察到的减少都可以得到解释，而不会使盘子变成负值，并且蘑菇只能通过巴塞洛缪的添加来积累。 

每个测试用例的输入大小最多为 1000 个观察值，最多为 100 个测试用例。 每个测试用例的二次或更差的解决方案在理论上仍然是可以接受的，但该结构表明线性扫描就足够了，因为每个步骤仅取决于先前的值。 任何重新计算全局最小值或尝试模拟所有可能的饮食计划的解决方案都是不必要的，并且存在效率低下的风险。 

当序列非递减时，会出现常见的边缘情况。 在这种情况下，第一种方法的结果为零，因为从未发生任何减少，而第二种方法的结果也为零，因为不需要强制进食率。 另一个微妙的情况是，当序列在长时间的平台期后急剧下降时，这可能会误导无法区分“由于进食而自然下降”和“所需的恒定消耗率”的实现。 

## 方法

 对于第一次计算，自然的方法是扫描相邻对并对序列中的所有液滴求和。 如果时间 i 的值大于时间 i+1 的值，则差异必定代表蘑菇因食用而消失。 将所有这些下降相加得出一个下限，实际上是精确的最小值，因为我们总是可以假设巴塞洛缪只添加蘑菇，而凯林吃的正是解释下降所需的东西。 

这是有效的，因为每个间隔都是独立的：增加不会限制饮食，而减少总是可以直接归因于消费而不影响未来的状态。 

第二个计算更加微妙，因为只要有蘑菇存在，凯琳的进食速度就会被限制为恒定速率。 关键的观察结果是，该比率由任何两个连续观察值之间的最大下降确定。 如果盘子在 10 秒的时间间隔内从 a 减少到 b，那么 Kaylin 在该时间间隔内一定至少吃了 (a − b) 个蘑菇。 由于每个间隔的长度相同，因此所需的速率是所有此类滴的最大值除以间隔长度。 一旦这个速率固定下来，我们就模拟这个过程：在每一步，我们假设 Kaylin 以这个速率进食 10 秒，下界为零，并且预期值和观察值之间的任何不足都可以通过添加来解释。 

蛮力的想法是尝试所有可能的进食速率并模拟每个速率的整个过程，检查可行性。 这太慢了，因为速率的范围可以达到数组中的最大值，并且每个模拟在 N 中都是线性的，从而给出二次或更糟糕的复杂性。 

只有最大单步下降才重要的观察结果将问题简化为单遍计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N * 最大值) | O(1) | O(1) | 太慢了|
 | 最佳| O(N) | O(1) | O(1) | 已接受 |

## 算法演练

 ###方法1（不限制饮食）

 1. 迭代连续的观察对。 
2. 每当序列从 m[i] 减少到 m[i+1] 时，将 m[i] − m[i+1] 添加到答案中。 
3. 忽略增加，因为它们可以通过添加新蘑菇来解释，而不是通过饮食行为来解释。 

每次减法都直接代表肯定已经消失的蘑菇，并且不同间隔之间不存在交互作用，因为模型允许任意进食时间。 

###方法2（恒定进食速度）

 1. 计算连续观测值之间的最大减少量。 这确定了最小可行恒定速率。 
2. 每 10 秒的时间间隔以该速度模拟进食。 
3. 每一步，吃的量是当前盘子值和速率中较小的一个。 
4. 将所有区间内吃掉的蘑菇求和。 

使用当前值取最小值的关键原因是，一旦盘子达到零，凯琳就不能吃更多，即使恒定速率表明她应该吃更多。 

### 为什么它有效

 在第一种方法中，每次减少都必须与消耗的蘑菇完全对应，因为没有其他机制可以减少数量。 这为每个区间创建了一个直接的守恒论证。 

在第二种方法中，恒定速率是由观察到的最差下降所强制的。 任何较小的利率都无法解释这种下降，而任何较大的利率在没有负计数的情况下都无法维持。 一旦确定，模拟就变得具有确定性：在给定添加量和有限消耗的情况下，板的演化是唯一的，因此总消耗完全由过程决定。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(arr):
    # Method 1: sum of all decreases
    y = 0
    for i in range(len(arr) - 1):
        if arr[i] > arr[i + 1]:
            y += arr[i] - arr[i + 1]

    # Method 2: determine eating rate
    rate = 0
    for i in range(len(arr) - 1):
        rate = max(rate, arr[i] - arr[i + 1])

    z = 0
    for i in range(len(arr) - 1):
        z += min(arr[i], rate)

    return y, z

def main():
    t = int(input())
    for tc in range(1, t + 1):
        n = int(input())
        arr = list(map(int, input().split()))
        y, z = solve_case(arr)
        print(f"Case #{tc}: {y} {z}")

if __name__ == "__main__":
    main()
```第一个循环通过聚合所有向下转换来计算总强制消耗。 第二个循环确定最差的下降，它定义了持续的饮食限制。 

最终的模拟假设 Kaylin 在每 10 秒的时间间隔内最多可以吃东西`rate`，但也不能吃超出现有量的食物。 这就是为什么`min(arr[i], rate)`正确限制消费。 

一个微妙的实现点是第二种方法并不连续模拟时间。 它仅考虑观察边界处的消耗，因为每个间隔都是均匀的。

 ## 边缘情况

 严格递增序列如`[1, 2, 3, 4]`两种型号均实现零消耗。 第一种方法永远不会遇到减少，因此不添加任何项。 第二种方法计算最大下降为零，导致进食率为零，因此模拟不会消耗任何东西。 

急剧下降然后恢复，例如`[10, 0, 10]`，由于第一次转换，强制第二个方法将速率设置为 10。 下一步，即使价值上升，消耗仍限制在当前值，总共吃掉20个。 第一种方法仅考虑单次下降，给出 10，这证实了本地下降计算与全局利率执行之间的分离。 

平坦的序列如`[0, 0, 0, 0]`永远不会触发任何一种机制。 两个计算始终保持为零，因为不存在降低或所需的速率。
