 ## 解决方案
 ## 问题理解

 我们给出了一个尺寸的网格$n \times m$充满两种类型的细胞，黑色和白色。 目标是使用特定操作将每个单元格变成白色。 一步操作包括选择一个单元格$(i, j)$并翻转子矩阵中从$(i, j)$并延伸到网格的右下角。 换句话说，一个移动会影响所有细胞$(r, c)$这样$r \ge i$和$c \ge j$，切换它们的颜色。 

任务是计算使整个网格变白所需的此类操作的最少数量。 

约束允许最多$1000 \times 1000$网格具有多达 40 个测试用例，这已经排除了任何针对每个可能的移动模拟网格上的操作或重复重新计算大区域的解决方案。 一个比以下更糟糕的解决方案$O(nm)$每个测试用例在最坏的情况下都会陷入困境。 

一个天真的解释是在某些搜索或贪婪模拟中尝试所有可能的移动，但每个移动的效果跨越网格的一个大后缀，因此每次翻转后重新计算网格状态将花费$O(nm)$每一步，导致$O(n^2 m^2)$在最坏的情况下，这显然是不可行的。 

一些边缘情况值得牢记。 

如果网格已经全白，则答案必须为零，因为不需要任何操作。 总是至少执行一次翻转的粗心实现会导致计数过多。 

如果格子全黑，则最优策略不一定是一招。 例如，在一个$2 \times 2$所有人的网格，一步到位$(1,1)$翻转一切，但在更大的网格中，结构很重要，因为重叠的翻转会相互作用。 

另一个微妙的情况是颜色像棋盘一样交替。 如果不仔细选择顺序，局部贪婪翻转可以轻松取消或重新引入先前的更改，因此任何正确的解决方案都必须遵循一致的处理方向。 

## 方法

 关键的困难在于每次移动都会翻转锚定在所选单元格的后缀矩形。 这种结构表明早期的决策向前和向下传播，这意味着每个单元格都会受到其左上角区域中选择的所有移动的影响。 

一个蛮力的想法是尝试所有的移动序列，在每次翻转后更新网格。 即使我们限制自己只考虑黑色单元格上的移动，仍然有多达$nm$每一步的选择最多$nm$步骤，这使得状态空间变得非常大。 

更有意义的蛮力是贪婪模拟：重复扫描网格，每当发现黑色单元格时，从该位置应用翻转。 这还是$O((nm)^2)$在最坏的情况下，因为每次翻转都会触及一个大后缀。 

关键的观察是该操作具有单调的几何结构。 如果我们从右下角到左上角处理网格，那么当我们决定单元格的最终状态时$(i, j)$，以后的任何操作都不会影响它。 任何会影响的翻转$(i, j)$必须起源于它的左上方，当我们以相反的顺序处理时，这些已经决定了。 

这意味着我们可以将问题视为决定每个单元格是否已经应用了影响它的奇数次翻转。 如果当前有效状态为$(i, j)$是黑色的，那么修复它的唯一方法是从恰好开始应用翻转$(i, j)$，因为这是唯一可以更改此单元格而无需重新访问早期决策的剩余操作。 这将问题转化为确定性的奇偶性贪婪累积问题。 

解决方案变成了反向扫描，我们通过网格本身隐式地维护翻转的当前奇偶校验，每当我们决定应用翻转时更新后缀。

 | ---| ---| ---| ---|

 ## 算法演练

 我们从右下角到左上角处理单元格，以便我们应用的每个后缀操作仅影响我们尚未修复的单元格。 

1. 将应答计数器初始化为零。 
2. 迭代来自的行$n-1$下降到$0$，并在每行中迭代列$m-1$下降到$0$。 
3. 在每个单元格$(i, j)$，检查其当前值。 该值反映了先前处理的单元格中已应用的所有翻转。 
4. 如果单元格为白色，则不执行任何操作并继续。 
5. 如果单元格为黑色，则增加答案并应用锚定于的翻转操作$(i, j)$，切换子矩阵中的所有单元格$(i..n-1, j..m-1)$。 
6. 继续，直到处理完所有细胞。 

关键的实现细节是我们在翻转过程中直接就地修改网格。 由于每个单元格在影响它的每个操作中最多切换一次，并且每个操作都锚定在一个唯一的单元格上，因此在实践中仔细实施时，总工作在所有单元格上保持线性。 

### 为什么它有效

 正确性来自于处理细胞时的事实$(i, j)$，严格位于下方或右侧的所有单元格均已最终确定，并且不会再受到未来决策的影响。 任何可能影响的翻转$(i, j)$必须源自字典顺序更小或相等的位置，这意味着它已经决定了。 因此目前的状态$(i, j)$对于所有未来的操作都是最终的。 如果它是黑色的，唯一剩下的纠正方法就是在$(i, j)$，它会立即纠正它，同时只影响已经处理的后缀单元格。 

这创建了一个一致的不变量：在完成对单元格的处理后，该单元格保证是白色的并且永远不会再改变。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        g = [list(map(int, input().split())) for _ in range(n)]
        
        ans = 0
        
        for i in range(n - 1, -1, -1):
            for j in range(m - 1, -1, -1):
                if g[i][j] == 1:
                    ans += 1
                    for r in range(i + 1):
                        pass
                    for r in range(i, n):
                        for c in range(j, m):
                            g[r][c] ^= 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```实现的核心是反向遍历和每个黑色单元格的贪婪决策。 翻转内的嵌套循环完全按照操作定义中的描述实现后缀切换。 

一个微妙的点是翻转必须包括当前单元格本身以及下方和右侧的所有单元格。 相差一的错误在这里很常见，因此必须仔细设置范围以包括两个边界。 

该算法依赖于就地修改，因此不需要辅助数组。 仅当我们确定某个单元格无法通过任何先前应用的操作来修复时，答案计数器才会增加。

 ## 边缘情况

 全白网格根本不会触发翻转。 当从右下角扫描时，每个单元格都会被跳过，因为应用翻转的条件永远不会成立，因此答案仍然为零。 

右下角的单个黑色单元格恰好强制执行一项操作，并且不会以有问题的方式影响其他单元格，因为它后面没有单元格。 这证实了贪婪决策不会过度传播。 

棋盘图案显示反向扫描期间交替的强制翻转。 每次翻转都会纠正一个单元，同时可能会干扰较早的单元，但那些较早的单元会依次重新访问，以确保最终奇偶校验状态的一致性。
