 ## 解决方案
 ## 问题理解

 每个测试案例都描述了胡安试图选择一家商店，从该商店购买飞行汽车所需的三个部件：发动机、方向盘和备用轮胎。 每家商店都提供这三种商品，但每家商店的价格不同。 Juan 不能在不同商店混合购买，因此如果他选择一家商店，他必须在那里购买所有三件商品。 

任务是针对每个测试用例计算三个价格相加时哪家商店的总成本最小。 商店按照它们在输入中出现的顺序进行考虑，如果多个商店达到相同的最低总成本，则必须选择最早的一家。 

这些约束足够大，以至于解决方案必须在所有测试用例中处理总共多达一千万个商店。 这立即排除了任何比每个测试用例的线性时间更糟糕的方法，因为当 n 重复达到一百万时，即使 O(n log n) 也会太慢。 唯一可行的方向是在恒定时间内计算每个商店的总和并保持运行最小值。 

在这个公式中，一些微妙的边缘情况自然出现。 一种是所有商店的总成本相同。 在这种情况下，答案必须是存储 1，而不是最后一次出现，这意味着平局处理必须偏向于看到的第一个最小值。 另一种情况是最小值在列表后面多次出现； 粗心的更新规则（例如“当当前总和小于或等于时更新”）会错误地偏向最后一个最小值而不是第一个最小值。 

## 方法

 解决该问题的直接方法是计算每个商店的总成本，将这些值存储在数组中，然后扫描最小值。 这是正确的，因为每个商店都是独立的，总成本只是其三个价格的总和。 然而，如果首先存储所有值，即使是这个简单的想法也可能效率低下，这将需要额外的内存和多次传递。 

瓶颈不是每个存储的计算，因为每个存储只需要三个加法，而是存储和重新处理大型输入的开销。 总共有多达 1000 万个存储，即使是第二次传递存储的数据也会面临缓存效率低下和内存压力的风险。 

关键的观察是我们永远不需要记住所有商店。 我们只需要当前最好的商店索引及其成本。 当我们阅读每家商店时，我们会计算其总成本，并立即将其与迄今为止看到的最佳成本进行比较。 这将问题简化为单个流传递。 

这是可行的，因为商店的决策不依赖于任何未来值。 最小值可以增量地维持：在任何时候，我们只关心当前存储是否改进了最佳已知答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（存储所有总数然后扫描）| 每个测试用例 O(n) | O(n) | 太慢/不必要的内存|
 | 流媒体最低 | 每个测试用例 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，读取商店数量 n。 这定义了我们将执行多少次独立比较。 
2. 初始化两个变量：best_cost 为无穷大，best_index 为 1。索引从 1 开始，因为商店编号是从 1 开始的，并且第一个商店是默认候选商店。 
3. 从 i = 1 到 n 迭代存储。 对于每个商店，读取三个价格并计算它们的总和。 该总和代表选择该商店的总成本。 
4. 将计算出的总和与 best_cost 进行比较。 如果当前总和严格较小，则将 best_cost 更新为该总和，将 best_index 更新为 i。 严格的不等式至关重要，因为它在存在关系的情况下保留了最早的索引。 
5. 处理完测试用例中的所有store后，输出best_index。

正确性依赖于维持这样的不变量：在处理第 i 个存储之后，best_cost 和 best_index 对应于前 i 个存储中的最小总成本，并且 best_index 是最早达到该最小值的位置。 由于每一步仅引入一个新的候选者并且从不重新访问过去的商店，因此该不变量在整个扫描过程中保持不变。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        
        best_cost = 10**30
        best_idx = 1
        
        for i in range(1, n + 1):
            a, b, c = map(int, input().split())
            total = a + b + c
            
            if total < best_cost:
                best_cost = total
                best_idx = i
        
        out.append(str(best_idx))
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案仅读取每个商店一次并立即评估其成本。 使用严格比较可确保关系不会覆盖较早的最佳索引。 在列表中累积输出并在最后写入一次可以避免重复的 I/O 开销，考虑到输入大小很大，这一点很重要。

 ## 边缘情况

 一个关键的边缘情况是多个商店共享相同的最低总成本。 例如：```
1
3
2 2 2
1 3 3
4 1 2
```所有总数均为 6。算法使用第一个存储来初始化 best_cost，并且仅更新严格较小的值。 在第一个存储上，best_cost 变为 6，best_idx 变为 1。第二个和第三个存储也产生 6，但由于 6 不小于 6，因此不会发生更新。 输出仍为 1，这符合所需的平局规则。 

另一个边缘情况是最好的商店是第一个商店，而后来的商店没有改进它。 该不变量确保不会发生不必要的更新，算法自然返回 1，无需特殊大小写。
