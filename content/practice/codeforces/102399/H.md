 ## 解决方案
 ## 问题理解

 我们有 (n) 个不同的正整数 (a_1,\ldots,a_n)。 一张卡片包含一些正整数 (x)。 有了这张卡，我们就可以对一个数组元素执行一次操作：将其乘以 (x)，或者在除法精确时将其除以 (x)。 之后该卡消失，因此相同的值（x）不能再次使用。 

目标是使所有数组元素相等，同时获取尽可能少的牌。 输入以升序给出元素的数量和不同的数组值。 输出是必须消耗的最少卡牌数量。 

原始竞赛语句有 1 秒时间限制和 512 MB 内存限制。 当 (n) 达到 (200,000) 时，(O(n^2)) 解决方案在最坏的情况下将执行大约 (4\cdot10^{10}) 对检查，这远远超出了一秒竞赛限制的范围。 我们需要一种本质上线性或接近线性的算法。 

有几个容易被忽视的细节。 首先，卡片是全球独一无二的。 如果两个元素都需要卡 (2)，则我们无法使用该卡执行这两个操作。 例如，```
5
2 3 6 12 18
```有答案（5），没有答案（4）。 选择最终值 (6) 看起来很有希望，因为每个元素都与 (6) 相当：所需的卡片值为 (3,2,2,3)。 重复的（2）和重复的（3）使该计划变得不可能。 如果粗心的解决方案仅检查整除性并对每个元素计算一次操作，则会错误地返回 (4)。 

其次，原始数组中不存在的最终值无法给出 (n-1) 解。 对于 (n-1) 次操作，至少有一个元素不接收任何操作，因为每个操作仅影响一个元素。 该未触及的元素保持等于其原始值，因此公共最终值必须是原始数组元素之一。 例如，```
3
6 10 15
```不能用两张卡来解决。 值 (30) 让每个元素通过一张牌到达目标，使用牌 (5,3,2)，但 (30) 不在数组中，因此必须更改所有三个元素。 正确答案是（3）。 

第三，(n=1) 需要零张牌，因为单个元素已经等于其自身。 例如，```
1
42
```有答案（0）。 这也是测试“所有元素相等”情况的唯一有意义的方法，因为输入保证数组元素是不同的。 

最后，在具有固定宽度整数的语言中，涉及 (10^{18}) 的算术需要小心。 尽管 Python 整数本身不会溢出，但即使是中间 LCM 也可能变得比 (10^{18}) 大得多。 该实现仍然限制了 LCM，因为一旦超过 (10^{18})，它就永远无法划分数组元素。 

## 方法

 直接的解决方案首先要观察到最终答案出人意料地受到限制。 

假设我们想使用 (k) 张卡片使每个元素相等。 每张卡片仅更改一个元素，因此如果 (k<n-1)，则至少有两个数组元素不会被触及。 它们最初是不同的，并且仍然是不同的，因此平等是不可能的。 因此每个解决方案至少需要 (n-1) 张卡。 

(n) 卡解决方案始终存在。 令 (g) 为所有数组元素的 GCD。 将每个 (a_i) 除以 (a_i/g)，将每个元素发送到 (g)。 所需的卡值都是不同的，因为原始 (a_i) 是不同的。 因此 (n) 张牌总是足够的。 

因此答案是 (n-1) 或 (n)。 

现在考虑什么时候 (n-1) 张牌是可能的。 只能有一个数组元素保持不变。 设其值为(y)。 由于最终值为 (y)，因此每个其他元素 (a_i) 必须在一次操作中恰好达到 (y)。 

一个操作只能在两种情况之一下将 (a_i) 更改为 (y)。 如果(a_i<y)，则(a_i)必须除以(y)，所需的牌为(y/a_i)。 如果(a_i>y)，则(y)必须整除(a_i)，所需的牌为(a_i/y)。 

所需的牌完全由(a_i)和(y)决定。 由于卡片不能重复使用，因此所有这些比率必须不同。 

因此，当每个其他数组元素在整除性下可与 (y) 进行比较时，元素 (y=a_i) 就是有效的 (n-1) 目标，并且所有结果比率都是不同的。 

剩下的问题是在不检查每个数组位置的所有 (n) 个元素的情况下找到所有可能的候选者。 

对于候选 (a_i)，每个较小的元素必须整除 (a_i)。 等价地，(i)之前的所有元素的最小公倍数必须整除(a_i)。 我们可以在扫描阵列时维护这个前缀 LCM。 LCM 的上限可以为 (10^{18}+1)，因为每个数组元素最多为 (10^{18})，因此较大的 LCM 永远无法划分候选者。 

类似地，每个较大的元素都必须能被 (a_i) 整除。 等价地，(a_i) 必须除以 (i) 之后所有元素的 GCD。 后缀 GCD 数组在恒定时间内给出了这个条件。 

候选人不可能有很多。 如果 (a_i) 和 (a_j) 都是候选者，且 (i<j)，则 (a_i) 的条件为 (a_i\mid a_j)。 由于值不同，(a_j\ge 2a_i)。 从正值开始且不超过 (10^{18})，这种情况最多可能发生约 60 次。 这使我们能够根据整个数组检查每个候选者。 

对于每个候选者，我们扫描数组，计算每个其他元素所需的卡片比率，并将该比率插入到集合中。 如果某个元素在任一方向上都不能被候选元素整除，则候选元素失败。 如果一个比率出现两次，则候选者也会失败，因为它需要同一张卡两次。 

蛮力方法检查所有 (n) 个可能的目标，并扫描每个目标的所有 (n) 个元素。 最坏的情况是 (O(n^2))，大约 (4\cdot10^{10}) 目标元素检查 (n=200,000)。 最优方法首先使用前缀 LCM 和后缀 GCD 过滤候选者，并且只有 (O(\log 10^{18})) 个候选者。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(n^2)) | (O(n)) | (O(n)) | 太慢了|
 | 最佳 | (O(n\log 10^{18})) | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

1.读取排序后的数组，构建后缀GCD数组。 对于每个位置 (i)，该数组存储严格位于 (i) 右侧的所有值的 GCD。 对于最后一个位置，后缀 GCD 是 (0)，这很方便，因为每个正整数都可以整除 (0)。 
2. 从左到右扫描数组，同时保持所有值的 LCM 严格位于当前位置之前。 如果此 LCM 超过 (10^{18})，则将其替换为大于 (10^{18}) 的特殊值。 这样的 LCM 永远无法划分任何候选数组元素。 
3. 仅当前缀 LCM 整除 (a_i) 且 (a_i) 整除后缀 GCD 时，才将 (a_i) 标记为可能的目标。 第一个条件表示每个较小的元素都可以通过一次操作到达 (a_i)。 第二个表示每个较大的元素都可以通过一次操作到达 (a_i)。 
4. 对于每个可能的目标 (y)，扫描除 (y) 之外的所有数组元素。 如果 (x<y)，则将所需的卡计算为 (y/x)。 如果 (x>y)，则将其计算为 (x/y)。 候选人保证这些划分是准确的，因此这里不需要额外的整除性测试。 
5. 将每个所需的比率插入到一组中。 如果相同的比例出现两次，则拒绝该目标，因为相应的牌在牌桌上只存在一次。 如果每个比率都不同，则目标给出有效的 (n-1) 卡结构，因此立即输出 (n-1)。 
6. 如果没有候选者起作用，则输出(n)。 前面描述的 GCD 结构保证 (n) 张牌总是足够的。 

### 为什么它有效

 下界 (n-1) 如下，因为较少的操作将使至少两个不同的原始元素保持不变。 (n-1) 运算解必须触及除一个元素之外的所有元素，因此其最终值必须等于未触及的元素。 然后，每个更改的元素都必须能够通过一次操作精确地转换为该目标，这在两个值可以以某种方式整除时恰好是可能的。 所需的卡是他们的商，因此所有商必须不同。 

前缀 LCM 条件完全等同于说每个较小的数组元素都可以划分候选值。 后缀 GCD 条件完全等同于说候选者可以划分每个较大的元素。 一旦满足这些条件，比率扫描就会检查唯一剩下的限制，即不需要卡值两次。 因此，当存在一个解时，算法恰好找到 (n-1) 个解。 如果没有找到，则下界排除每个较小的答案，并且 GCD 构造提供 (n) 卡解决方案，因此 (n) 是最优的。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

LIMIT = 10**18
INF = LIMIT + 1

def solve_case(a):
    n = len(a)

    # suffix_gcd[i] = gcd(a[i], ..., a[n-1])
    # We need the gcd strictly after i, so suffix_gcd[i + 1].
    suffix_gcd = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suffix_gcd[i] = math.gcd(a[i], suffix_gcd[i + 1])

    candidates = []

    # pref_lcm is the LCM of elements strictly before i.
    pref_lcm = 1

    for i, x in enumerate(a):
        if pref_lcm <= LIMIT and x % pref_lcm == 0:
            if suffix_gcd[i + 1] % x == 0:
                candidates.append(i)

        if pref_lcm <= LIMIT:
            g = math.gcd(pref_lcm, x)
            multiplier = x // g

            if pref_lcm > LIMIT // multiplier:
                pref_lcm = INF
            else:
                pref_lcm *= multiplier

    # Try every possible untouched element.
    for idx in candidates:
        target = a[idx]
        used = set()

        for x in a:
            if x == target:
                continue

            if x < target:
                card = target // x
            else:
                card = x // target

            if card in used:
                break

            used.add(card)
        else:
            return n - 1

    return n

def main():
    n = int(input())
    a = list(map(int, input().split()))
    print(solve_case(a))

if __name__ == "__main__":
    main()
```后缀GCD数组是从右到左构建的。`suffix_gcd[i + 1]`恰好包含position之后的元素`i`，所以检查`suffix_gcd[i + 1] % x == 0`处理候选人的右侧。 

前缀 LCM 仅在测试当前元素后更新，因为候选元素本身不能是前缀的一部分。 LCM 计算为 (L/\gcd(L,x)\cdot x)，这避免了不必要的公因子乘法。 

(10^{18}+1) 处的上限是性能和清晰度的衡量标准。 一旦前缀 LCM 大于 (10^{18})，以后的数组值就不能被它整除，因为所有数组值最多为 (10^{18})。 我们永远不需要知道确切的更大的 LCM。 

在候选验证期间，可分性条件已经建立。 这使得代码可以直接使用整数除法，而不是对每个元素执行另一个模运算。 

该集合包含卡片值，而不是转换后的数组值。 即使两个元素从不同的值开始，它们也可能需要相同的商，而这正是候选者必须被拒绝的情况。 

Python具有任意精度的整数，因此计算LCM时不会溢出。 显式上限仍然可以防止 LCM 变得不必要的大，并保持操作受到限制。

 ## 边缘情况

 对于单个元素，```
1
42
```候选是(42)，前缀LCM是(1)，后缀GCD是(0)。 候选有效，比率集为空，算法返回（1-1=0）。 无需任何操作。 

对于重复的卡要求，```
5
2 3 6 12 18
```候选人（6）通过了可分性条件。 其所需的比率为(3,2,2,3)。 该集合立即检测到 (2) 的第二次出现，因此 (6) 无法提供 (n-1) 个解。 其他可能的候选者不满足整除条件，给出正确答案 (5)。 

对于数组外部的目标，请考虑```
3
6 10 15
```值 (30) 可被所有三个元素整除，并且比率 (5,3,2) 不同。 这给出了有效的三张牌结构，但它不能给出两张牌结构，因为没有一个原始元素是 (30)。 通过两项操作，其中一个元素必须保持不变，并强制最终值为 (6,10,15) 之一。 算法正确返回 (3)。 

对于接近上限的值，```
2
999999999999999999 1000000000000000000
```两个数字都不能整除另一个数字。 没有原始值可以成为单卡目标，因此答案不能是（1）。 两张牌就足够了，每个数字除以（1）即可，所以答案是（2）。 该实现也从不依赖乘法产生高于 (10^{18}) 的值。 

对于大前缀 LCM，上限很重要。 假设前缀包含 LCM 已经超过 (10^{18}) 的值。 未来的数组值不能被该前缀 LCM 整除，因为每个未来值最多为 (10^{18})。 该实现将 LCM 替换为 (10^{18}+1)，因此所有后面的候选都将被拒绝，而无需构造巨大的整数。 

对于最大输入大小，数组```
1 2 3 ... 200000
```有 (200,000) 个不同的值。 目标 (1) 需要卡片 (2,3,\ldots,200000)，全部不同，所以答案是 (199999)。 候选者立即通过前缀 LCM 条件找到，并且比率扫描确认每张所需的卡都是唯一的。
