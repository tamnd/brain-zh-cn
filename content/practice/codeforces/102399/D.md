 ## 解决方案
 ## 问题理解

 我们有一个城市的有向加权图。 城市`1`是首都，每一条有方向的道路`u -> v`有能力`w`，表示最多重量的货物`w`可以穿过那条路。 

对于固定城市`s`，一条从`s`到首都可以走几条路。 相同的货物必须在路线上的每条道路上幸存下来，因此该特定路线支持的最大货物重量是其沿线的最小边缘容量。 我们需要最好的路线，所以答案为`s`是所有路线中的最大值`s`到`1`，该路线上的最小边缘容量。 如果没有通往首都的路线，答案是`-1`。 

官方的限制是`n <= 10^5`和`m <= 10^6`，有 2 秒时间限制和 512 MB 内存限制。 道路的数量足够多，以至于算法可以做任何接近的事情`O(nm)`是不可能的。 甚至`O(n^2)`太大时`n`达到`10^5`。 我们需要以大致线性或`m log n`时间。 边缘容量最多为`10^9`，因此 Python 整数可以直接处理它们，而无需担心溢出。 

道路的方向造成了第一个常见的陷阱。 我们正在询问以城市为终点的路径`1`，而不是从那里开始的路径。 例如：```
2 1
2 1 5
```答案是`5`。 如果我们不小心从城市进行普通搜索`1`在原始图表上，城市`2`无法到达，因为唯一的道路指向`1`。 

第二个陷阱是采用路线上最大的边而不是最小的边。 考虑：```
3 2
3 2 10
2 1 3
```答案是：```
3
```能力之路`10`超出能力范围没有帮助`3`路。 一条航线的容量是其瓶颈。 

第三个陷阱是接受找到的第一条路径。 考虑：```
4 4
2 1 2
2 3 8
3 4 7
4 1 7
```城市的答案`2`是：```
7
7
-1
```立即采取的 DFS`2 -> 1`会记录`2`， 虽然`2 -> 3 -> 4 -> 1`支持重量`7`。 该问题要求最好的路径，而不仅仅是任何可达的路径。 

最后，必须保留无法到达的城市`-1`。 例如：```
3 1
2 1 4
```输出是：```
4
-1
```粗心的初始化，例如`answer[v] = 0`可以使一个无法到达的城市看起来好像零重量运输是可能的，即使所需的答案是明确的`-1`。 

## 方法

 直接的暴力解决方案是枚举从每个城市到首都的路径。 对于每条路径，通过采用最小边缘容量来计算其瓶颈，然后保留该起始城市看到的最大瓶颈。 这是正确的，因为每条可能的路线都会被检查。 

问题在于路径的数量。 在完全有向图中，从一个源枚举简单路径的 DFS 可能会遇到`P(n-1,1) + P(n-1,2) + ... + P(n-1,n-1)`不同的路径，在哪里`P(a,b) = a! / (a-b)!`。 在所有起始城市中，这个顺序是`n!`，远远超出了可以处理的范围`n = 10^5`。 除非添加访问状态处理，否则循环会使粗心的路径枚举变得更糟。 

暴力破解之所以有效，是因为答案是由路径的最小边缘容量定义的，但它会失败，因为它单独处理每个可能的路径。 有用的观察是路径的价值可以用一个数字（其瓶颈）来概括。 一旦我们知道了从城市到首都可实现的最佳瓶颈，再延长一条道路只会通过最少的操作改变该值。 

还有一个方向问题。 因为每个答案都描述了一条通往城市的路线`1`，反转每条路。 一条原始的路`u -> v`容量`w`变成反向边缘`v -> u`具有相同的容量。 现在有从首都到`u`在反向图中正好对应于从`u`到原始图中的首都。 

这将问题转化为从城市开始的最大瓶颈路径问题`1`。 我们可以用 Dijkstra 式的贪心算法来解决。 我们没有选择最小的暂定距离，而是反复选择当前已知瓶颈最大的未处理城市。 如果当前城市有价值`best[v]`和一个反向边缘`v -> u`有能力`w`，然后达到`u`通过`v`支持`min(best[v], w)`。 

如果该值提高`best[u]`，我们将新值推入最大堆。 使 Dijkstra 工作的贪婪排序在这里也是有效的，因为每个扩展都适用`min`，这永远不会增加已知路径的价值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数，`O(n!)`在密集图中|`O(n + m)`加上递归/路径状态 | 太慢了|
 | 最佳 |`O((n + m) log n)`|`O(n + m)`| 已接受 |

 ## 算法演练

 1. 构建反转图。 对于每一条原始的道路`u -> v`有能力`w`, 存储一条边`v -> u`具有相同的容量。 这使得远离城市`1`在新图中相当于向城市移动`1`在原始图表中。 
2. 创建`best[v]`，目前已知到达城市的最大瓶颈运力`v`从城市`1`在反转图中。 放`best[1]`为无穷大，因为尚未使用任何道路，并将所有其他值设置为`-1`因为那些城市还没有到达。 
3. 放置`(infinity, 1)`进入最大优先级队列。 蟒蛇的`heapq`是一个最小堆，因此将容量存储为其负数并使用`(-capacity, vertex)`。 
4. 从堆中删除具有最大已知瓶颈的城市。 如果堆条目已过时，因为`best[v]`已经变大了，丢弃它。 这与 Dijkstra 算法常用的延迟删除技术相同。 
5. 对于每个反向边`v -> u`有能力`w`，计算到达时得到的瓶颈`v`然后越过这条边：```
candidate = min(best[v], w)
```如果`candidate > best[u]`， 更新`best[u]`并将新值推入堆中。 最小值是必要的，因为货物必须满足已经过的部分和新道路的要求。 

1. 继续，直到堆为空。 此时，反转图中从首都可到达的每个城市都有其最大可能的瓶颈。 每个城市仍然等于`-1`无法到达原图中的首都。 
2. 输出`best[2]`,`best[3]`, ...,`best[n]`。 城市`1`本身没有要求。 

### 为什么它有效

 不变的是，每当一个城市`v`是用当前最大瓶颈提取的，其值已经是最优的。 假设有更好的路径`v`。 考虑该更好路径上尚未提取的第一个顶点。 其在同一路径上的前身必定已经被提取，因为资本首先被提取并且路径在反向图中向外前进。 当处理该前趋时，算法将插入下一个顶点的候选，该候选顶点等于更好路径前缀的瓶颈。 该候选人至少是声称的瓶颈`v`。 由于队列总是首先提取最大的候选者，`v`无法用更小的值提取。 因此，每个最终值都是最优的。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    # rev[v] contains (u, w) for every original edge u -> v with weight w.
    rev = [[] for _ in range(n)]

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        rev[v].append((u, w))

    best = [-1] * n
    best[0] = 10**18

    # Python has a min-heap, so store negative bottlenecks.
    pq = [(-best[0], 0)]

    while pq:
        neg_value, v = heapq.heappop(pq)
        value = -neg_value

        # Ignore an outdated heap entry.
        if value != best[v]:
            continue

        for u, w in rev[v]:
            candidate = min(value, w)

            if candidate > best[u]:
                best[u] = candidate
                heapq.heappush(pq, (-candidate, u))

    sys.stdout.write("\n".join(map(str, best[1:])))

if __name__ == "__main__":
    solve()
```输入循环将每条道路转换为反向邻接条目。 如果原来的路是`u -> v`，达到`v`在相反的图表中，让我们转向`u`，所以将其存储在`rev[v]`正是所需的转换。`best[0]`被初始化为`10**18`，它安全地大于每个可能的边缘容量。 它也可以初始化为符号无穷大，但使用整数可以使瓶颈计算变得简单。 第一个转变就变成了`min(10**18, w) = w`。 

优先级队列包含负值，因为`heapq`实现一个最小堆。 因此，具有最大实际瓶颈的顶点具有最小的存储负数并且首先被提取。 

一个顶点可能会多次进入堆。 例如，可能首先达到容量`3`后来改进为`7`。 该代码没有搜索堆来删除旧条目，而是将其留在那里。 当老`(3, v)`条目被弹出，`value != best[v]`，因此被忽略。 这使实现变得简单并保留了预期的`O((n+m) log n)`边界。 

比较的是`candidate > best[u]`， 不是`>=`。 相等的值不会改善任何东西，并且避免重复的相等堆条目对于具有许多相同容量的道路的图表很有用。 

图算法内部没有基于一的索引操作。 城市转换自`1..n`到`0..n-1`立即，所以城市`1`是顶点`0`。 最后一片`best[1:]`完全从输出中移除资本。 

Python整数不会溢出，所有容量都是正数且最多`10^9`。 额外的`10**18`哨兵仅用于资本，从不出现在输出中。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O((n + m) log n)`| 每次成功的松弛都会插入一个堆条目，并且每条边都会从其反向邻接列表中检查一次。 |

 ## 边缘情况

 第一个边缘情况是相反的方向。 为了```
2 1
2 1 5
```反转图包含`1 -> 2`有能力`5`。 该算法从城市开始`1`，放松城市`2`和`min(infinity, 5) = 5`，和输出`5`。 从城市搜索原始图`1`将会失败，这正是逆转是必要的原因。 

第二个边缘情况是瓶颈计算。 为了```
3 2
3 2 10
2 1 3
```反转图包含`1 -> 2`有能力`3`和`2 -> 3`有能力`10`。 城市`2`获得价值`3`，然后是城市`3`收到`min(3, 10) = 3`。 输出是`3`，即使一条路可以承载`10`。 

第三个边缘情况是竞争路线。 为了```
4 4
2 1 2
2 3 8
3 4 7
4 1 7
```反转图以候选人开始`2`对于城市`2`和`7`对于城市`4`。 城市`4`首先被提取，因为`7 > 2`。 它的城市边缘`3`有能力`7`，所以城市`3`收到`7`。 加工城市`3`然后给出城市`2`候选人`min(7, 8) = 7`，替换其先前的值`2`。 最终结果是`7, 7, 7`。 

第四种边缘情况是无法到达的顶点：```
3 1
2 1 4
```逆转后，唯城`2`从城市可到达`1`。 堆永远不会发现城市`3`， 所以`best[3]`停留`-1`。 输出是`4`其次是`-1`。 这就是为什么`-1`是一个有用的初始状态而不是`0`。
