 ## 解决方案
 ## 问题理解

 我们得到了一系列排成一行的砖块。 每块砖都有一个单位的宽度和一定的高度。 我们还有固定的行宽，这意味着我们只能将有限数量的砖块并排放置在单行中。 

构造规则很简单：我们开始从左到右填充一行。 每行最多可以容纳固定数量的砖块。 一旦一行被填满，我们就在它的正下方开始一个新行，并继续以相同的顺序放置砖块。 一行的高度不是砖块高度的总和，而是该行中放置的所有砖块的最大高度。 墙的总高度是这样形成的所有行的高度之和。 

因此，任务简化为将砖块高度数组划分为大小最多为给定宽度的连续块，取每个块中的最大值，并对这些最大值求和。 

输入大小限制通常允许最多大约十万块砖块。 这立即排除了任何二次或更糟的情况，因为 O(n²) 方法在最坏的情况下将涉及数百亿次运算，这远远超出了两秒的限制。 对每个砖块进行一次处理的线性扫描就足够了。 

当最后一行未完全填充时，会出现微妙的边缘情况。 例如，如果宽度为 4 并且最后一组仅包含两块砖，例如`[5, 1]`，该行的高度仍然是`5`，不是平均或部分调整。 另一个边缘情况是当所有砖块完全适合行时，每个组的大小都完全相同`w`，并且我们必须确保不会由于循环边界错误而意外地跳过最后一组的处理。 

## 方法

 思考该问题的一种直接方法是完全按照所描述的方式模拟行构造。 我们迭代砖块，维护当前行中已放置的砖块的运行计数，并跟踪迄今为止在该行中看到的最大高度。 当该行变满时，我们将最大值添加到答案中，重置计数器，然后继续。 

这种模拟在结构上已经是最佳的，因为每个砖块都必须至少被读取一次。 更幼稚的变体会尝试将每一行显式构造为列表，然后在填充后计算其最大值。 这仍然会导致线性总工作，但由于重复的列表分配和扫描而导致更高的恒定开销。 另一个不正确的天真的想法是将数组预先分割成块，然后单独计算最大值，这是等效的，但如果每个块重新计算值而不是增量地维护它们，则可能实现效率低下。 

关键的观察结果是，我们在放置砖块后永远不需要重新访问它。 每行所需的唯一信息是迄今为止遇到的最大高度，因此我们可以在扫描时增量维护该值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 显式行构造 + 重新计算最大值 | O(n) | O(n) | 已被接受但效率低下|
 | 具有滚动最大值的单通道模拟 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从左到右处理砖块，维护两个状态：当前放置在活动行中的砖块数量，以及迄今为止在该行中看到的最大高度。 

1. 将总答案初始化为零，并将当前行计数和当前行最大值设置为零。 
2. 按顺序迭代每个砖块。 对于每个砖块，通过将其与砖块的高度进行比较来更新当前行最大值。 这确保我们始终知道当前行中最高的砖块。 
3. 增加当前行中的砖块数量，因为我们又在其中放置了一块砖块。 
4. 如果当前行达到允许的宽度，我们通过将其最大高度添加到总答案中来最终确定该行。 然后我们重置行计数并重置当前最大值，因为新行会立即开始。 
5. 处理完所有砖块后，如果还剩下部分填充的行，我们也会将其最大高度添加到答案中。 此步骤至关重要，因为最后一行可能不会触发全角完成。 

仅维护运行最大值背后的原因是行高仅取决于该段中最高的砖块，并且未来的操作无法更改已完成的行。 

### 为什么它有效

 每块砖都属于一行，纯粹由其在序列中的索引确定。 该算法将数组划分为连续的长度段`w`（可能除了最后一个）。 在每个段中，我们使用增量更新精确计算一次最大高度。 由于行高仅由最大值定义，并且行是独立的，因此将这些最大值相加即可得出正确的总墙高。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, w = map(int, input().split())
    h = list(map(int, input().split()))
    
    total = 0
    cur_max = 0
    cnt = 0
    
    for x in h:
        cur_max = max(cur_max, x)
        cnt += 1
        
        if cnt == w:
            total += cur_max
            cnt = 0
            cur_max = 0
    
    if cnt > 0:
        total += cur_max
    
    print(total)

if __name__ == "__main__":
    solve()
```代码直接反映了算法。 这`cnt`变量跟踪当前行中已放置了多少块砖，确保我们知道一行何时完成。 这`cur_max`变量维护当前段中最高的砖块，而不需要存储整个段。 最后的条件加法处理不完整的最后一行。 

一个常见的错误是忘记重置`cur_max`当开始一个新行时。 如果错过此重置，则前一行的最大值会错误地污染下一行，从而夸大结果。

 ## 边缘情况

 当只有一块砖且宽度为 1 时，算法会处理一次更新，立即完成该行，并返回该高度。 部分行逻辑没有机会干扰，结果基本上是正确的。 

当宽度大于砖块数量时，整个序列形成一个不完整的行。 该算法永远不会触发循环内的全行条件，因此最终的`if cnt > 0`block 确保返回整个数组的最大值，该最大值与定义匹配。 

当所有砖块高度相同时，所有段中每行的最大值保持相同。 滚动最大值永远不会改变，并且每个完成的行都贡献相同的值，从而确认该算法不依赖于输入的变化来正确运行。 

当序列长度是宽度的精确倍数时，最后一行始终在循环内完全处理，并且不会触发尾随条件。 这可确保不会出现重复计数或遗漏片段。
