 ## 解决方案
 ## 问题理解

 我们得到一个以十进制形式写成的非常大的正整数。 我们要从这个数字中减去另一个正整数$b$，由我们在两个约束下选择。 第一的，$b$必须严格小于给定的数字。 其次，如果我们计算差异$c = a - b$， 然后$c$必须是正整数，其十进制表示形式由每个位置重复的相同数字组成，例如$7$,$4444$， 或者$111111$。 

任务不是找到任何有效的对，而是选择$b$使其变得尽可能小。 自从$b = a - c$，最小化$b$相当于制作$c$尽可能大，同时仍然是重复数字并且严格小于$a$。 

输入大小的长度比数值大小更重要。 该数字最多可以有数千万位，因此任何尝试对许多候选值进行逐位算术或重复模拟减法的解决方案都会失败。 唯一可行的操作是输入的线性扫描以及长字符串之间的少量恒定数量的比较。 

一个天真的但常见的错误是假设最好的选择$c$始终是与以下位数相同的最大重复数字$a$。 当较短的重复数字如$999\ldots9$少一位数字仍然比在某些前缀下的任何有效的相同长度候选者大$a$。 另一个微妙的陷阱是试图构建$c$贪婪地逐位数字，而不考虑repdigit的结构强制所有数字相同，这使得本地选择无效。 

## 方法

 一个蛮力的想法是枚举所有可能的重复数字$c$，从中减去它们$a$，并取最小的结果$b$。 重复数字由长度决定$k$和一个数字$d$从 1 到 9，给出如下值$d \times (111\ldots1)$。 此类候选人的数量呈线性增长$k$， 和$k$本身可以与中的位数一样大$a$。 

问题不在于候选人的数量，而在于评估每个候选人的成本。 对一个数进行每次减法和比较，最多可达$10^7$数字与该大小呈线性关系。 即使测试几百个候选者也是不可能的，因为每个测试都已经很大了。 

关键的观察是最佳答案的结构受到极大限制。 repdigit 的位数要么与$a$，或者恰好少了一位数字。 任何短两位或更多位的重复数字都太小，无法与相同长度的重复数字竞争，因为添加一位数字位置会使幅度至少乘以 10，而数字范围仅为 1 到 9。这会极大地压缩搜索空间。 

因此，问题减少为仅检查两种情况：长度相同的最佳重复数字$a$，以及长度的最大重复数字$|a| - 1$，这始终是$999\ldots9$。 答案来自于产生有效的较小值的那个$c$并赋予更大的价值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有重复数字进行暴力破解 |$O(n^2)$数字运算 |$O(n)$| 太慢了|
 | 仅检查长度$n$和$n-1$候选人 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 让$a$是作为长度字符串的输入数字$n$。 

### 1. 尝试使用与以下相同长度的 redigits$a$我们尝试构造一个数$c$长度$n$其中所有数字都等于某个值$d$9 到 1 之间。我们想要最大的这样的$c$严格小于$a$。 

我们迭代$d$从 9 到 1 并比较字符串$d$重复$n$次与$a$。 第一个较小的数字是该长度的最佳候选，因为较大的数字在字典顺序和数字上产生较大的数字。 

此步骤之所以有效，是因为在等长十进制数中，字典顺序与数字顺序相匹配。 

### 2. 构建最佳的较短重复数字

 我们还考虑长度的重复数字$n-1$。 最好的选择永远是$999\ldots9$，因为增加任何数字只会使数字变大，同时仍保持在相同的长度内。 

我们不需要尝试其他数字来达到这个长度，因为任何小于全 9 的值都严格来说更差。 

### 3. 比较两位候选人

 我们现在最多有两名有效候选人$c$。 我们选择较大的，因为较大$c$意味着更小$b = a - c$。 

如果相同长度的候选者都不起作用，则答案必须来自较短的候选者。 

### 为什么它有效

 关键的属性是重复数字在数轴上形成一个非常稀疏的集合，并且它们的大小由长度而不是数字选择决定。 任何长度最多的候选者$n-2$至多是$9 \cdot (10^{n-2} - 1)/9$，小于$10^{n-1} - 1$，这意味着它总是小于每个$n-1$-数字重复数字。 这保证了只有前两个长度才重要。 

在固定长度内，所有有效数字都按数字选择单调排序，因此对数字的搜索就足够了，不需要考虑中间结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def repdigit(d, k):
    return str(d) * k

def less(a, b):
    if len(a) != len(b):
        return len(a) < len(b)
    return a < b

def main():
    a = input().strip()
    n = len(a)

    best_c = "0"

    # case 1: same length
    for d in range(9, 0, -1):
        c = str(d) * n
        if c < a:
            best_c = c
            break

    # case 2: length n-1
    if n > 1:
        c2 = "9" * (n - 1)
        if less(best_c, c2):
            best_c = c2

    # compute b = a - best_c (big integer subtraction)
    a_digits = list(map(int, a[::-1]))
    c_digits = list(map(int, best_c[::-1]))

    b = []
    carry = 0
    for i in range(n):
        ai = a_digits[i]
        ci = c_digits[i] if i < len(c_digits) else 0
        val = ai - ci - carry
        if val < 0:
            val += 10
            carry = 1
        else:
            carry = 0
        b.append(str(val))

    while len(b) > 1 and b[-1] == '0':
        b.pop()

    print("".join(b[::-1]))

if __name__ == "__main__":
    main()
```候选者的构建分为两个严格限制的搜索。 在实践中，数字 9 到 1 上的第一个循环是恒定时间，并且仅执行相等长度的字符串比较，这是线性的$n$。 第二个候选者直接构造为一串 9。 

最后使用标准的逐位方法以相反的顺序执行一次减法。 由于只需要一次减法，因此这不会影响运行时间。 

## 工作示例

 ### 示例 1

 让$a = 239$。 

我们首先尝试相同长度的重复数字：999太大，888太大，777太大，666太大，555太大，444太大，333太大，222小于239，所以$c = 222$。 

较短的候选者是 99，它小于 222，所以我们保留 222。 

| 步骤| 候选人$c$| 与比较$a$| 迄今为止最好的 |
 | --- | --- | --- | --- |
 | 尝试 9 | 999 | 更大| 无 |
 | 尝试 2 | 222 | 222 较小| 222 | 222
 | 更短| 99 | 99 小于 222 | 222 | 222

 然后$b = 239 - 222 = 17$。 

这证实了最大化相同长度的重复数字已经可以主导较短的选项（当它存在时）。 

### 示例 2

 让$a = 10055$。 

相同长度的重复数字都是5位统一数字。 比较从 99999 到 11111 的任何此类数字，但所有数字都大于 10055。因此没有相同长度的候选值。 

我们回到较短的候选人$c = 9999$。 

然后$b = 10055 - 9999 = 56$。 

| 步骤| 候选人$c$| 与比较$a$| 迄今为止最好的 |
 | --- | --- | --- | --- |
 | 相同长度 | 全部被拒绝| 全部 > 10055 | 无 |
 | 更短| 9999 | 有效 | 9999 |

 这表明考虑短一位数的重复数字的重要性，它可以完全确定答案。

 ## 边缘情况

 当$a$略高于 10 的幂，例如$1000\ldots0$，所有以 9 中的 1 位或多位数字开头的相同长度的重复数字都是有效的候选数字，并且算法通常会正确选择最大的数字$999\ldots9$，确保减法产生一个小的$b$。 

什么时候$a$已经接近重复数字，例如$222\ldots2$，相同长度的候选人变得非常有竞争力。 该算法仍然按降序检查所有数字级别，因此它自然会选择最接近的有效重复数字，而不需要任何特殊处理。 

什么时候$a$长度为 2，两个候选长度实际上是相同的，并且逻辑仍然成立，因为较短的情况减少为一位数字 redigit，它与两位数候选进行了正确的比较。
