 ## 解决方案
 ## 问题理解

 我们得到一个整数数组。 每个操作都以一种非常具体的方式修改该数组：我们定位两个特殊位置，一个包含最大值，一个包含最小值。 最大值被选择为所有最大值中最左边出现的位置，而最小值被选择为所有最小值中最右边出现的位置。 一旦确定了这两个位置，我们就计算它们的平均值，向下舍入，并将该值分配给这两个位置。 

重复这个过程 k 次后，我们必须输出结果数组。 

约束允许数组大小最大为 200,000，操作次数最多为 n。 这立即表明，从头开始为每个操作重新计算最大值和最小值会太慢，因为每次扫描成本为 O(n)，导致最坏情况下为 O(nk)，从而退化为 O(n^2)。 那太大了。 

一个关键的微妙之处是极值的位置不稳定。 更新两个元素可能会改变下一个最大值或最小值出现的位置，因此我们需要一个支持点更新下重复全局查询的结构。 

边缘情况是由打破平局规则产生的。 最大值必须是最左边的出现，而最小值必须是最右边的出现。 忽视平局决胜的幼稚方法将会失败。 

例如，考虑 [5,1,5]。 最大值为 5，正确的选择是索引 0。最小值为 1，索引 1。经过一次操作，两者都变为 3，生成 [3, 3, 5]。 如果程序错误地选择了最右边的最大值，它将选择索引 2 并更改错误的元素，从而产生错误的未来状态序列。 

另一个微妙的情况是更新后最大值和最小值的值甚至位置一致。 该算法仍然必须将它们视为具有正确平局打破的两个独立选择，即使它们在转换后最终指向相同的索引。 

## 方法

 直接模拟很简单：对于 k 个操作中的每一个，扫描数组以查找所需的最大和最小索引，计算平均值并更新两个位置。 这是正确的，但每次扫描的成本为 O(n)，从而导致 O(nk)。 当 n 达到 200,000 时，这变得不可行。 

关键的观察结果是，尽管值发生变化，但每次操作仅更新两个位置。 数组的其余部分保持不变。 这表明维护一个能够有效跟踪全局最大和最小点更新的数据结构就足够了。 

线段树是很自然的选择。 每个节点存储按最小索引进行平局的最大值，以及按最大索引进行平局的最小值。 每次更新两个位置后，我们都会以 O(log n) 的时间更新线段树，如果存储在根处，查询两个极值的时间为 O(1)。 

因此，每个操作变为 O(log n)，总复杂度变为 O(k log n)，这很容易足够快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nk) | O(nk) | O(n) | 太慢了|
 | 线段树| O(k log n) | O(k log n) | O(n) | 已接受 |

 ## 算法演练

 我们维护一棵线段树，其中每个节点存储两条信息：线段中的最大值及其最左边出现的索引，以及线段中的最小值及其最右边出现的索引。

1. 在初始数组上构建线段树。 每个叶子存储其值和索引，内部节点根据平局规则选择正确的最大值和最小值来合并子节点。 这确保我们始终可以从根检索正确的全局极值。 
2. 重复以下过程 k 次。 在每次迭代时，从根节点读取最大值。 这给出了最左边最大值的值和索引。 
3. 同样从根节点读取最小值，给出最右边最小值的值和索引。 
4. 计算新值作为这两个值的平均值的下限。 该值将替换两个选定的位置。 
5. 如果两个选定的索引相同，我们只执行一次更新； 否则，我们更新数组中的两个位置并将这些更改传播到线段树中。 
6.经过k次迭代后，输出最终的数组。 

我们可以重复查询根的关键原因是每次更新只影响两个位置，并且线段树在每次修改后都维护正确的聚合信息。 

### 为什么它有效

 在每一步，线段树都正确地表示当前数组。 根节点始终存储具有正确平局决胜的真实全局最大值，以及具有其平局决胜规则的真实全局最小值。 由于每个操作仅更改两个位置，并且线段树更新保留所有祖先的正确性，因此该不变量在所有 k 个步骤中保持有效。 因此，所选的每一对索引都正是问题定义所需的索引，确保模拟与预期过程相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("mx", "mx_i", "mn", "mn_i")
    def __init__(self, mx=0, mx_i=0, mn=0, mn_i=0):
        self.mx = mx
        self.mx_i = mx_i
        self.mn = mn
        self.mn_i = mn_i

def merge(a, b):
    res = Node()

    if a.mx > b.mx:
        res.mx, res.mx_i = a.mx, a.mx_i
    elif a.mx < b.mx:
        res.mx, res.mx_i = b.mx, b.mx_i
    else:
        res.mx = a.mx
        res.mx_i = min(a.mx_i, b.mx_i)

    if a.mn < b.mn:
        res.mn, res.mn_i = a.mn, a.mn_i
    elif a.mn > b.mn:
        res.mn, res.mn_i = b.mn, b.mn_i
    else:
        res.mn = a.mn
        res.mn_i = max(a.mn_i, b.mn_i)

    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size <<= 1
        self.t = [Node(-10**18, 0, 10**18, 0) for _ in range(2 * self.size)]

        for i in range(self.n):
            v = arr[i]
            self.t[self.size + i] = Node(v, i, v, i)

        for i in range(self.size - 1, 0, -1):
            self.t[i] = merge(self.t[2 * i], self.t[2 * i + 1])

    def update(self, idx, val):
        i = self.size + idx
        self.t[i] = Node(val, idx, val, idx)
        i //= 2
        while i:
            self.t[i] = merge(self.t[2 * i], self.t[2 * i + 1])
            i //= 2

    def root(self):
        return self.t[1]

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    st = SegTree(a)

    for _ in range(k):
        r = st.root()

        mx_val, mx_i = r.mx, r.mx_i
        mn_val, mn_i = r.mn, r.mn_i

        new_val = (mx_val + mn_val) // 2

        if mx_i == mn_i:
            st.update(mx_i, new_val)
        else:
            st.update(mx_i, new_val)
            st.update(mn_i, new_val)

    print(*[st.t[st.size + i].mx for i in range(n)])

if __name__ == "__main__":
    solve()
```该解决方案是围绕同时维护两个极值的线段树构建的。 每个节点都使用其所需的平局索引来跟踪最大值和最小值。 合并功能独立地强制两个统计数据的正确性。 

更新操作重建从叶子到根的路径，确保每次修改后的一致性。 由于仅执行 k 个操作，因此更新总数受 O(k log n) 限制。 

一个小但重要的细节是，当最大和最小索引重合时，我们只执行一次更新。 如果没有这项检查，我们就会错误地重复应用相同的转换，从而破坏正确性。

 ## 边缘情况

 一种关键的边缘情况是最大值和最小值出现在同一索引处。 例如，在像 [5] 这样的数组中，由于 n ≥ 2，这种情况不会发生，但更新后，所有元素可能会变得相等。 在这种情况下，两个极值都指向相同的索引。 该算法明确地检查这一点并执行单次更新，保持正确性并避免冗余写入。 

另一种微妙的情况是存在多个最大值或最小值时。 每一步都必须严格执行决胜规则。 线段树存储索引信息，以便即使在更新后，查询仍保持一致。 例如，在 [1, 5, 5] 中，最大值在索引 1 处选择，而不是在索引 2 处，并且此选择可以在未来的操作中正确传播。
