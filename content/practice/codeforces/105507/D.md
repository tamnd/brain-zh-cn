 ## 解决方案
 ## 问题理解

 给定两个长度相等的字符串，均由小写拉丁字母组成。 唯一允许的操作获取当前字符串的第一个字符，将其删除，然后将其重新插入字符串中的任何位置，包括向后插入到前面或末尾。 该操作可以重复任意次。 目标是确定将初始字符串转换为目标字符串所需的此类操作的最少数量，或者决定根本无法完成。 

从操作本身观察到的关键是我们从不删除或创建字符，因此两个字符串之间的多重字符集必须保持相同。 这立即给出了一个必要条件：如果两个字符串之间任何字符的频率不同，则任何操作序列都无法解决该问题，因为我们只排列字符。 

这些约束允许长度高达 200,000 的字符串，这会立即排除任何二次模拟转换或任何显式重复重建字符串的方法。 任何在嵌套循环中多次重新访问字符的解决方案都会太慢。 我们应该瞄准线性或接近线性的过程，最有可能涉及贪婪扫描或类似队列的模拟。 

当字符在多重集中匹配但无法按顺序对齐时，会出现微妙的边缘情况。 例如，s =“ab”和 t =“ba”有效，但 s =“ab”和 t =“ac”由于计数不匹配而不可能。 另一个有趣的情况是当 s 和 t 是大量重复的排列时； 如果天真的贪婪交换策略假设可以任意放置角色而不考虑未来的约束，那么它们可能会失败。 

## 方法

 蛮力视角是明确模拟该过程。 我们维护字符串并重复获取第一个字符并尝试所有可能的插入位置。 这产生了一个巨大的分支因子：每个步骤有 O(n) 个选择，并且最多可以有 n 个步骤，因此搜索空间呈指数增长。 即使修剪也没有足够的帮助，因为状态空间本质上是通过约束旋转可达到的所有排列，这仍然是巨大的。 

关键的结构见解是该操作不允许任意交换，但它确实允许我们通过将当前前面的字符发送到后面或任何后面的位置来“推迟”当前的前面字符。 换句话说，我们从左到右扫描字符串，但允许延迟那些对构建目标字符串不会立即有用的字符。 

这将问题重新构建为 s 和 t 之间的贪婪匹配过程。 我们尝试按顺序匹配 t，同时从前面扫描 s。 每当 s 的当前前面字符与 t 中的下一个所需字符匹配时，我们就会消耗这两个字符。 当它不匹配时，我们将该字符视为被移走（到后面），支付一次操作，然后继续。 

这种贪婪的想法避免了明确地探索所有插入位置。 唯一的决定是当前角色是否有助于我们在 t 方面取得进展，还是必须推迟。

 | --- | --- | --- | --- |
 | 暴力枚举插入| 指数| O(n) | 太慢了 |
 | 贪婪队列模拟 | O(n) 摊销 | O(n) | 已接受 |

 ## 算法演练

 我们使用源字符串的类似队列的结构和目标字符串的指针来模拟这两个字符串。

1. 首先，我们验证两个字符串具有相同的字符数。 如果不是，我们立即返回 -1，因为没有任何操作序列可以调和差异。 
2. 我们在目标字符串上维护一个指针 j，最初为 0，表示我们要匹配的下一个字符。 
3. 我们将源字符串视为队列。 我们反复检查它的正面特征。 
4. 如果前面的字符等于 t[j]，我们将两个指针都前移。 这相当于将该角色放置在其正确的最终相对位置而无需推迟，因此不会产生任何操作成本。 
5. 如果前面的字符与 t[j] 不匹配，我们模拟执行允许的操作：将其删除并将其插入到字符串末尾，将操作计数器增加 1。 
6. 我们继续这个过程，直到目标字符串的所有字符都匹配。 

关键的想法是我们永远不需要显式选择插入位置。 任何无用的字符都会被简单地推回，从而保持正确性，因为它的最终位置是由它最终变得有用的时间隐式确定的。 

### 为什么它有效

 在任何时刻，我们都在尝试对齐 t 中的下一个所需字符。 如果队列的前面已经匹配，则延迟它只会增加操作而没有任何好处。 如果不匹配，则将其保留在前面会阻止 t 的进展，因此必须推迟。 这会产生一个贪婪的不变量：每个字符要么在与所需目标位置匹配时立即被消耗，要么在阻止进度时准确推迟。 这确保我们不会进行不必要的推迟，也不会错过有效的比赛机会。 

因为每个字符要么以模拟中严格前进指针的方式匹配或向后移动，所以该过程在 t 的进度方面是单调的，因此它不能无限循环或失去最优性。 

## Python 解决方案```python
import sys
from collections import Counter, deque

input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    t = input().strip()

    if Counter(s) != Counter(t):
        print(-1)
        return

    dq = deque(s)
    j = 0
    ops = 0

    while j < n:
        if dq[0] == t[j]:
            dq.popleft()
            j += 1
        else:
            dq.append(dq.popleft())
            ops += 1

    print(ops)

if __name__ == "__main__":
    solve()
```该解决方案首先使用字符计数进行可行性检查，因为任何不匹配都会导致无论进行何种操作都无法进行转换。 主要模拟使用双端队列来表示不断演变的字符串。 指针 j 跟踪目标字符串的进度。 

每一步要么消耗一个匹配的字符，要么将前面的字符旋转到后面，算一次操作。 一旦 t 的所有字符都匹配，循环就会结束。 

一个微妙的实现细节是我们总是访问 dq[0]，因此当 j < n 时双端队列绝不能为空。 这是可以保证的，因为两个字符串具有相同的长度，并且我们仅在匹配或移动字符时删除字符，从而在模拟的循环意义上保持大小一致性。

 ## 边缘情况

 一种重要的边缘情况是目标字符串需要一个存在但当前被阻塞在队列深处的字符。 例如，s =“baaa”，t =“aaab”。 该算法重复旋转前导“b”，直到有足够的“a”字符到达前面。 模拟可确保“b”在变得相关之前准确地按需要推迟多次。 

另一种情况是 s 已经等于 t 时。 在这种情况下，每次比较都会立即成功，因此不会执行任何旋转，结果为零。 该算法自然地处理这个问题，因为第一次比较总是成功并推进两个指针而不触发任何操作。 

最后的边缘情况是字符串具有相同的多重集但需要大量重新排列，例如完全反转。 即使在这种情况下，每个不匹配都通过一次旋转来处理，并且每个字符一旦到达目标序列正确阶段的前面，最终就会精确对齐，从而确保整个结构的线性进展。
