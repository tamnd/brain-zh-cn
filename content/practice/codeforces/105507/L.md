 ## 解决方案
 ## 问题理解

 我们有一组球员，每个人都有不同的身高。 我们希望将所有现有球员排成一行，并可能添加新球员，以便最终阵容形成完美连续的身高序列。 这里的“完美”是指从左到右排列后，每对相邻的人的身高相差正好一，最左边的人可以从任意高度开始。 

因此，任务不是重新排列任意复杂的约束，而是在通过插入新玩家填充缺失值后，将给定的分散整数集转换为某个整数区间的子集，且间隙不大于 1。 每个插入的球员都会贡献一个最初不存在的缺失整数高度。 

输出是我们必须插入的附加整数的最小数量，以便所有给定值都可以嵌入到至少一个完整的连续整数运行中。 

约束高达 200000 个不同高度，因此成对玩家之间的任何二次比较都会立即变得太慢。 解决方案本质上必须是基于排序的或排序后是线性的，因为 O(n log n) 是可接受的，而 O(n^2) 则不可接受。 

一个微妙的点是，最终序列不需要从最小给定高度开始，也不需要在最大给定高度结束。 我们可以选择包含所有选定高度的任何区间，如果这减少了插入，我们可以超出它们。 这使得它成为一个覆盖区间问题，而不仅仅是计算输入范围内的间隙。 

一个天真的错误是假设我们只需要填充连续排序高度之间的间隙。 例如，对于高度 1、10、20，简单地对相邻对之间的缺失值求和会忽略我们可能会选择更长的间隔来更好地对齐并减少插入。 另一个错误是假设答案仅取决于 max 减去 min，当存在较大的内部间隙，无论端点如何都会强制进行多次插入时，该答案就会失败。 

## 方法

 蛮力的想法是尝试可能包含最终照片线的每个可能的目标区间 [L, R]。 对于每个选择，我们检查给定高度中缺少该区间中的多少个整数，并在包含所有原始值的所有区间中取最小值。 这是正确的，因为任何有效的最终阵容都精确对应于包含所有原始高度的某个区间。 

然而，这种方法变得不可行，因为 L 和 R 的变化范围可达 10^9，因此不可能枚举区间。 即使我们限制以输入值为界的间隔，仍然有 O(n^2) 个候选者，并且检查每个候选者在最坏的情况下会导致 O(n^3) 行为。 

关键的观察是我们实际上不需要测试任意间隔。 如果我们固定一个起点 L，则最佳 R 就确定了：它应该包括所有给定的高度，因此 R 必须至少为 max(ai)。 一旦 L 固定，成本直接由 [L, max(ai)] 中缺少多少个整数决定。 这将问题简化为最优选择 L。 

排序后，最佳 L 将始终与现有高度之一对齐。 如果 L 放置在两个值之间，则将其右移到最接近的现有值只会减少或保留所需插入的数量，而不会失去可行性。 这将问题转化为评估所有排序位置作为可能的左端点。 

对于等于 a[i] 的固定 L，所需的最终区间长度为 max(a) - a[i] + 1。该区间内已存在元素的数量只是从索引 i 开始的元素计数，因为所有内容都是不同且已排序的。 所以插入的玩家数量就是间隔长度减去可用元素。

 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) | O(n^3) | O(1) | O(1) | 太慢了|
 | 最佳 | O(n log n) | O(n log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 按升序对高度数组进行排序。 这是必要的，因为我们想要推理连续的整数间隔，并且排序将问题转换为连续索引对应于增加的高度的结构。 
2. 令最大高度为排序后的最后一个元素。 如果我们选择给定的起点，则该值充当任何有效最终间隔的强制右边界。 
3.对于每个索引i，将a[i]视为最终连续序列的候选起始高度L。 这是合理的，因为任何最佳间隔都可以移动，直到其左边界与现有高度重合，而无需增加所需插入的数量。 
4. 对于 L = a[i] 的选择，计算达到最大值所需的完整整数段的长度：max(a) - a[i] + 1。这表示从 a[i] 开始到 max(a) 结束的完美序列中必须存在多少个不同的整数高度。 
5. 计算有多少原始玩家属于该细分市场。 由于数组已排序，因此从索引 i 到 n-1 的所有元素都在该区间内，因此它们的计数为 n - i。 
6. 此区间所需的新玩家数量是所需段大小与现有元素之间的差值：(max(a) - a[i] + 1) - (n - i)。 
7. 取所有 i 中的最小值。 这会选择最佳的起点，即最小化丢失整数的起点。 

### 为什么它有效

 该算法依赖于以下不变量：任何最佳最终排列都对应于完全包含所有选定原始高度的连续整数区间。 对于任何这样的间隔，向右滑动其左端点直到达到现有高度永远不会增加丢失整数的数量，因为它只会从左侧删除未覆盖的值，而不会影响最大所选元素施加的右边界约束。 因此，将注意力限制在等于现有值的起点上可以保持最优性。 一旦左边界固定，通过计算强制区间内缺失的整数数量直到全局最大值来完全确定成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
a.sort()

mx = a[-1]

ans = n  # upper bound: at worst we fill everything between min and max

for i in range(n):
    length = mx - a[i] + 1
    have = n - i
    need = length - have
    if need < ans:
        ans = need

print(ans)
```解决方案首先对高度进行排序以施加结构。 最大值被提取一次，因为我们考虑的每个候选区间都在那里结束； 任何省略它的最佳解决方案都会更糟，因为扩展以包含它只会扩大可用范围，而不会增加所需的连续性约束。 

对于每个可能的起始索引，该公式计算从该高度到最大值的整个区间内缺少多少个整数。 减法`n - i`之所以有效，是因为排序保证了从 i 开始的所有元素都在区间内。 这避免了显式的成员资格检查或设置操作。 

初始值`ans`可以安全地从 n 开始，因为在最坏的情况下，我们可能需要插入最多 n-1 或更少的值，这作为一个简单的上限。 没有边缘情况需要特殊处理，因为循环自然地评估 i = n-1 处的极端起点。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    a.sort()
    mx = a[-1]
    ans = n
    for i in range(n):
        ans = min(ans, mx - a[i] + 1 - (n - i))
    return str(ans)

 ## 边缘情况

 对于单个元素输入，例如`[100]`，算法对其进行排序，将最大值设置为 100，并仅计算一个长度为 1 的区间。计算出的需求为零，因为除了单个点之外不需要连续性。 

对于完全连续的数组，例如`[5, 6, 7, 8]`，每次迭代计算为零，因为间隔长度始终与包含的元素数量匹配。 该算法正确地识别出无论起始位置如何都不需要插入。 

对于高度稀疏的值，例如`[1, 1000000000]`，最佳选择是从任一端点开始，但计算始终会产生一个大间隔减去两个现有元素，从而产生等于完整缺失范围减去现有点的正确插入数量。
