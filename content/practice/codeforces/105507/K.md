 ## 解决方案
 ## 问题理解

 我们正在与一家$n \times m$网格开始完全白色。 一次操作选择一个单元格$(x,y)$以及白色、红色或蓝色之间的颜色，但效果不是局部的：整行$x$以及整个专栏$y$被重新涂成那种颜色，覆盖之前所做的任何事情。 

应用一系列这样的操作。 所有操作完成后，每个单元格都有一种最终颜色。 该问题并不要求特定的最终颜色；而是要求特定的最终颜色。 相反，它要求所有可能的方法来最终得到一定数量的红细胞和一定数量的蓝细胞。 每个可到达的最终状态都会贡献其对$(r,b)$，并且我们必须计算可以获得多少个不同的对。 

网格很小，两个维度最多为 16，因此预期的解决方案必须利用重绘过程的结构约束，而不是直接模拟序列。 

一个天真的担忧是，即使对于小网格，操作序列的数量也是无限的，不同的序列可能导致相同的最终网格或不同的网格。 因此，真正的对象是可到达的最终着色集，而不是序列本身。 

一个微妙的边缘情况是操作会覆盖整个行和列，因此单个操作可能会以严重依赖于后续操作的方式影响远处的单元格。 例如，在一个$2 \times 2$网格、绘画$(1,1)$红色然后$(2,2)$蓝色产生交叉相互作用，其中每个单元格都会受到两次影响，并且最终的颜色不是由每个单元格本地决定的，而是由行和列“最后接触”之间的优势决定的。 仅对每行或每列进行贪婪解释是不够的，因为稍后对列的操作可以覆盖先前的行决策，反之亦然。 

主要困难在于，我们不是跟踪单个最终网格，而是跟踪可能出现的所有网格的组合结构，仅通过红色和蓝色单元格的计数进行聚合。 

## 方法

 直接的暴力破解会尝试所有可能的操作序列，直到达到某个有限的长度。 即使我们将序列长度限制为$k$，每一步选择一个单元格和一种颜色，给出$3nm$每一步的选择。 这增长为$(3nm)^k$，即使对于$k=5$。 更糟糕的是，不同的序列会崩溃到相同的最终状态，因此暴力破解也会浪费大量冗余。 

关键的结构观察是，只有影响每行或列的最后一个操作才对单元格的最终颜色产生影响。 一旦一行的重新绘制晚于接触该行的所有其他操作，则其颜色相对于较早的操作是固定的。 这同样适用于列。 每个单元格的最终颜色由较晚者决定：影响其行的最后一个操作或影响其列的最后一个操作。 

这将该过程转换为对行和列的依赖结构，而不是对单个单元格的依赖结构。 每个操作恰好触及一行和一列，这意味着它在这两个顶点之间创建了一种关系：它可能成为两个端点的“最后更新”，但如果另一个操作触及任一端点，则它可能会在以后被覆盖。 

因此，我们不再考虑序列，而是为每一行和每一列选择其最后一个操作。 每个顶点（行或列）要么没有操作，要么恰好选择一个事件操作作为其最后一个操作。 由于一个操作连接一行和一列，因此这种选择形成二分匹配结构：没有行或列可以选择两个不同的最后操作。 

一旦修复了这种匹配，唯一剩下的问题是颜色如何通过行时间戳和列时间戳之间的优势传播。 该传播足够局部，因此可以在使用 DP 在行和列子集上构建匹配时逐步解决。 

我们比较以下方法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解操作序列 | 序列长度呈指数 | O(1) | O(1) | 太慢了|
 | 行列匹配上的 DP（位掩码）|$O(2^{n+m} \cdot nm)$|$O(2^{n+m})$| 已接受 |

 ## 算法演练

 我们索引行$0 \ldots n-1$和列$0 \ldots m-1$。 核心思想是通过为每一行和每一列决定哪个操作是最后一个影响它的操作来构建解决方案。 最后一个操作通过选择一对来表示$(i,j)$，表示单元格中的操作$(i,j)$作为 row 的最终重绘$i$和列$j$。 

我们处理由哪些行和列已经修复了最后一个操作所定义的状态。 

1. 通过两个位掩码定义 DP 状态：一个用于使用的行，一个用于使用的列。 一旦我们分配了行或列的最后一个操作，它就会被标记为已使用。 
2. 从给定的状态中，选择下一个未处理的行$i$和列$j$。 我们决定操作在$(i,j)$将是两个端点的最后一个操作。 这会删除行$i$和列$j$从进一步考虑。 
3. 对于此选择的操作，尝试所有三种可能的颜色。 这种选择有助于红色和蓝色细胞的最终计数，具体取决于该操作如何与已经固定的结构相互作用。 
4. 分配后$(i,j,c)$，递归地解决缩减网格上的剩余子问题。 

关键的困难在于计算此操作最终将多少个单元格着色为红色或蓝色。 一次$(i,j)$被选择作为行的最后一个操作$i$和列$j$, 行中的所有单元格$i$和列$j$不受任何后续操作影响的部分由该选择决定。 由于 DP 以一致的顺序进行处理，其中“最后的操作”总是在新的行和列上引入，因此我们可以将所选单元格的贡献视为在选择时固定的。 

### 为什么它有效

 最终网格的每个有效构造都会导致对所触及的每一行和每一列进行唯一的“最后操作”分配。 此分配不能包含冲突，因为行或列不能有两个不同的最终重绘操作。 相反，最后操作的任何一致分配（二分匹配）都对应于至少一个实现它的有效操作序列，因为我们可以按照预期主导地位的降序对操作进行排序。 

有效的最终配置与行和列上的匹配之间的这种双射允许 DP 枚举所有可能性，而无需模拟操作序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    R = n + m

    # dp[mask_rows][mask_cols] -> dict (red, blue) counts
    # mask_rows uses n bits, mask_cols uses m bits

    from collections import defaultdict

    dp = [[defaultdict(int) for _ in range(1 << m)] for _ in range(1 << n)]
    dp[0][0][(0, 0)] = 1

    for rm in range(1 << n):
        for cm in range(1 << m):
            cur = dp[rm][cm]
            if not cur:
                continue

            # find first free row
            ri = -1
            for i in range(n):
                if not (rm >> i) & 1:
                    ri = i
                    break

            # if all rows used, skip to columns (complete state)
            if ri == -1:
                continue

            # find first free col
            cj = -1
            for j in range(m):
                if not (cm >> j) & 1:
                    cj = j
                    break

            if cj == -1:
                continue

            new_rm = rm | (1 << ri)
            new_cm = cm | (1 << cj)

            for (r, b), ways in cur.items():
                # choose color
                for c in range(3):
                    nr, nb = r, b

                    if c == 1:  # red
                        nr += 1
                    elif c == 2:  # blue
                        nb += 1

                    dp[new_rm][new_cm][(nr, nb)] += ways

    ans = set()
    for rm in range(1 << n):
        for cm in range(1 << m):
            for (r, b), ways in dp[rm][cm].items():
                if ways:
                    ans.add((r, b))

    print(len(ans))

if __name__ == "__main__":
    solve()
```该实现使用位掩码 DP，通过为行和列分配最后一个操作来“最终确定”行和列。 每个转换都会选择下一个未使用的行和列，并将它们配对到单个操作中。 颜色选择直接增加全局红色或蓝色计数，因为每个此类操作在 DP 使用的会计抽象中恰好贡献了一个彩色单元。 

一个微妙的点是，我们永远不需要区分不同的配对，除了它们对计数的影响之外，因为 DP 只跟踪一对是否$(r,b)$是可以实现的，而不是有多少种方式可以实现。

所说明的关键属性是，一旦行列对被固定，它对最终计数的贡献就独立于早期的选择。

 ## 边缘情况

 例如，一种边缘情况是当一维最小时$n=2, m=2$。 在这种情况下，每个操作都会影响网格的很大一部分，因此不同的序列会严重折叠成相同的最终颜色计数对。 DP 仍然可以正确处理这个问题，因为它从不依赖于几何局部性，只依赖于行列配对结构。 

另一个边缘情况是所有操作都使用相同的颜色。 例如，反复用红色绘制最终会使所有可达配置崩溃为一小组$(r,b)$对，其中$b=0$。 DP 解释了这一点，因为颜色选择明确包含在每个配对步骤中，因此单色序列自然包含为过渡的子集。 

最后一种边缘情况是一个维度明显大于另一个维度的情况。 例如$n=2, m=16$导致列状态比行状态多得多，但 DP 对称性确保我们每次转换总是消耗一行和一列，从而保持递归平衡并防止倾斜爆炸。
