 ## 解决方案
 ## 问题理解

 我们被要求仅使用两种硬币类型支付准确的金额，一种价值 2 个单位，另一种价值 5 个单位。 目标不仅仅是确定是否可以形成总和，而是构造一个总价值恰好是所需数量的硬币组合，并使用尽可能少的硬币。 

每个解决方案对应于选择一定数量的 5 值硬币和一定数量的 2 值硬币，以便加权和与目标匹配。 在所有有效的组合中，我们必须最小化所使用的硬币总数。 

对目标值 n 的限制最大为 100 万。 这个大小立即排除了任何在两种硬币类型的嵌套循环中尝试硬币计数的所有组合的方法，因为即使对可能的计数进行二次扫描也会太慢。 一维上的线性或近线性扫描是可以接受的。 

一个微妙的点是，可行性是有保证的，所以我们永远不需要处理不可能的情况。 这消除了回溯或复杂奇偶推理来检测不可行性的需要，但我们仍然必须确保我们的贪婪选择不会意外地破坏精确的总和要求。 

当贪婪选择“取尽可能多的 5”超出或留下不能被 2 整除的余数时，就会出现典型的边缘情况模式。例如，如果 n 很小或与模 10 的某些余数一致，则天真的贪婪方法可能会失败，除非向下调整 5 个硬币的数量。 

## 方法

 暴力策略会枚举我们拿走了多少个 5 值的硬币，比如 k，然后检查是否可以使用 2 值的硬币形成剩余的值 n − 5k。 这意味着验证 n − 5k 是否为非负且偶数，如果是，则将总硬币数计算为 k 加 (n − 5k)/2。 尝试从 0 到 n/5 的所有 k 给出 O(n) 可能性，并且每次检查都是 O(1)，因此总复杂度是 O(n)。 虽然这已经符合约束条件，但没有必要明确检查每种可能性，因为问题的结构强烈约束最优解决方案。 

关键的观察结果是，在减少单位价值硬币数量方面，5 面值硬币总是比 2 面值硬币更有效。 然而，由于 5 是奇数，而 2 是偶数，奇偶校验约束可能迫使我们用多个 2 硬币替换一个 5 硬币。 这就产生了一个单向调整问题：我们想要尽可能多的 5 个硬币，但我们可能需要减少它们的数量，直到剩余的总和可以被 2 整除。 

这导致了贪婪策略：从最大可能数量的 5 个硬币开始，然后递减它，直到实现可行性。 由于我们只向下移动并且每一步都检查一个简单的奇偶校验条件，因此该过程在 O(n/5) 最坏情况下运行，但实际上它受到常数因子的限制（由于模 2 约束，最多几步）。 每次测试的时间复杂度实际上是 O(1)。

 ## 算法演练

 我们通过尝试最大化 5 值硬币的数量，然后用 2 值硬币修复剩余部分来构建解决方案。

1. 计算 5 个硬币的最大可能数量 k = n // 5。这给出了不超过 n 的最大起点。 我们的想法是，使用较大的硬币会减少总数，因此我们从最积极地压缩总和开始。 
2. 当 k 为非负数时，检查剩余的值 r = n − 5k 是否可以仅使用 2 值硬币来表示。 当 r 为偶数时，这是可能的，因为 2 是唯一可用的偶数单位。 
3. 如果 r 是偶数，则将 2 个硬币的数量计算为 r // 2 并返回 k + r // 2 作为答案。 这种组合是最佳的，因为我们在可行的情况下最大化了较大硬币的数量。 
4. 如果 r 是奇数，则将 k 减 1 并重复。 此步骤相当于用额外的 2 个硬币替换一个 5 个硬币，这会翻转剩余的奇偶校验并可能恢复可行性。 

关键的不变量是，在每次迭代中，我们都用恰好 k 个五枚硬币来测试最佳可能的解决方案。 由于价值限制，任何使用超过 k 个五枚硬币的解决方案都是不可能的，并且由于奇偶校验不匹配，仅在必要时才考虑使用更少的任何解决方案。 因此遇到的第一个可行的 k 产生最小数量的硬币。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    k = n // 5

    while k >= 0:
        rem = n - 5 * k
        if rem % 2 == 0:
            print(k + rem // 2)
            return
        k -= 1

solve()

if __name__ == "__main__":
    solve()
```代码直接遵循贪婪结构。 我们从最大可能数量的 5 个硬币开始，并通过奇偶校验检查可行性。 余数检查`rem % 2 == 0`是唯一需要的条件，因为被 2 整除完全表征了使用 2 值硬币的可表征性。 

一个常见的实现陷阱是忘记循环必须一次减少 k 步，而不是跳跃 2。奇偶校验会随着每次递减而交替，因此跳过值可能会丢失第一个可行的配置。

 ## 边缘情况

 当 n 很小时，例如 n = 4，算法从 k = 0 开始，因为不能使用 5 个硬币。 余数是 4，是偶数，因此它立即返回 2 个价值 2 的硬币。 

对于 n = 7，k 从 1 开始，余数为 2，即偶数，因此算法正确返回 1 个 5 硬币和 1 个 2 硬币。 这是最优的，因为任何使用零个 5 个硬币的尝试都需要 3 个 2 个硬币，这会更糟糕。 

对于 n mod 5 为 1 或 3 的值，初始贪婪选择 k = n // 5 始终会产生奇数余数。 然后循环减小 k 直到余数变为偶数，从而保证在不跳过最佳配置的情况下找到有效的分解。
