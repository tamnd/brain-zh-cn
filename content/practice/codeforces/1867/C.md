 ## 解决方案
 ## 问题理解

 我们得到一组已排序的不同整数。 我们不直接控制这个集合； 相反，我们通过改变对手的动作与对手互动。 

每次移动，我们要么在集合中插入一个新数字，要么允许鲍勃在限制下删除一个数字。 Bob 只能删除严格小于我们最近插入的数字的值。 这在连续移动之间创建了耦合：每次插入都可能为 Bob 解锁有限的删除窗口。 

游戏继续进行，直到鲍勃无法再删除任何内容或达到固定的移动限制。 最后，我们计算最终集合的 MEX，这意味着不存在的最小非负整数。 

目标是选择插入的数字，以便在双方的最佳发挥下，最终的 MEX 最大化。 

n 最大为 100000 的约束意味着我们无法模拟任何有意义的分支或对游戏状态的搜索。 每一步都必须在常数或对数时间内确定。 由于这是交互式的，即使 O(n log n) 只有在非常干净的情况下才是可接受的，但任何涉及每次移动重复扫描集合或重新计算 MEX 的操作都会导致 TLE 或不同步交互。 

当人们假设鲍勃总是可以立即删除任何小数字时，就会出现一种微妙的失败情况。 这是不正确的，因为删除取决于最后插入的值。 例如，如果集合同时包含 0 和 1，并且我们首先插入一个非常小的数字，那么鲍勃将无法访问该集合的较大部分，直到我们提高插入阈值。 总是插入当前 MEX 的幼稚贪婪策略可能会意外地给 Bob 太多机会删除低值。 

关键的困难在于，MEX 不仅受到数字存在的影响，还受到互动动态中存活下来的小数字的数量的影响。 

## 方法

 暴力视图会尝试模拟博弈树。 在任何状态下，Alice 选择插入一个未使用的号码，Bob 通过删除有效号码进行响应，我们在跟踪最终 MEX 的同时递归直到终止。 这很快就会呈指数增长，因为每次移动都会打开多个有效的删除和插入。 即使单个步骤也有 O(n) 分支，使得整个游戏变得棘手。 

关键的观察是，爱丽丝的选择不是为了构造任意的最终集合，而是为了控制小整数是否能在鲍勃的删除中幸存下来。 由于 MEX 仅依赖于从 0 开始的整数前缀的存在，因此整个游戏简化为控制 Bob 可以持续删除低于所选阈值范围内的元素的时间。 

一个有用的思考方法是，每次插入 x 都会定义一个“保护边界”：Bob 只能删除低于 x 的值。 如果 Alice 总是逐渐插入更大的值，Bob 的删除能力就会逐渐扩大，但只是以受控的方式。 事实证明，最佳策略是围绕确保从 0 开始的所有整数都有效地尽早强制进入集合，同时防止 Bob 在我们通过足够大的插入“锁定”它们之前有选择地删除它们。 

这将问题简化为构建一个序列，确保最终重新引入或保留小于最终 MEX 的每个整数，同时仔细管理 Bob 的删除窗口，这样他就无法永久删除所需的前缀元素。 

标准最优构造依赖于尽可能插入当前最小的缺失非负整数，因为这样做要么迫使 Bob 将其有限的删除花费在小值上，要么使他无法阻止前缀的形成。

 ## 算法演练

 正确的策略是在集合的演化过程中维持当前的 MEX，并始终尝试扩展从 0 开始的连续整数的前缀。 

1. 计算给定集合的初始 MEX。 这是最初不存在的最小整数。 该值是自然目标边界，因为低于该值的值已经部分受到初始配置的约束。 
2. 维护指针`cur`从 0 开始，代表我们仍然希望确保在最终集合中生存的最小整数。 
3. 在每次 Alice 移动时，插入`cur`如果它尚未在集合中。 原因是最终的 MEX 完全取决于我们可以将这个连续前缀增长多远，因此尝试注入缺失的前缀元素始终是 Bob 的最佳压力。 
4.插入后`cur`，阅读鲍勃的回复。 如果 Bob 删除了某个值，请相应地更新该集合。 
5. 如果 Bob 删除的值小于`cur`，我们不改变`cur`。 这反映出当前的前缀候选仍然是正确的下一个目标，因为删除较小的值不会影响我们稍后重建前缀的能力。 
6. 如果 Bob 删除了等于`cur`，我们必须认识到当前的前缀尝试已被中断，因此我们重试插入`cur`再次在下一步行动中。 
7. 什么时候`cur`成功出现在集合中并且不能被 Bob 的响应永久拒绝，增量`cur`到下一个整数并继续。 

关键思想是，只有当目标前缀在 Bob 的约束删除下变得稳定时，我们才会推进目标前缀。 

### 为什么它有效

 不变量是，在任何时刻，所有整数`[0, cur)`有效地保护在集合中，鲍勃不能永久删除它们，除非允许爱丽丝在未来的移动中立即重建它们。 由于 Bob 的删除受到最后插入的值的限制，因此 Alice 始终可以通过在需要时重新插入来重新获得对任何丢失的前缀元素的控制。 结果，Bob 永远无法可靠地打破前缀的增长超出最佳 MEX 边界，而 Alice 最终迫使前缀在最佳发挥下尽可能扩展。 

这将游戏简化为稳步扩展受保护的整数前缀，这直接决定了最终的 MEX。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def mex_of_set(s):
    m = 0
    while m in s:
        m += 1
    return m

t = int(input())
for _ in range(t):
    n = int(input())
    arr = list(map(int, input().split()))
    s = set(arr)

    cur = 0
    while cur in s:
        cur += 1

    # we try to extend mex greedily
    while True:
        print(cur)
        sys.stdout.flush()

        y = int(input())
        if y == -2:
            exit()
        if y == -1:
            break

        if 0 <= y <= 10**9:
            s.discard(y)

        # if current is now in set, advance
        if cur in s:
            cur += 1
```该解决方案维护当前候选 MEX 边界并始终尝试插入该值。 每次鲍勃移动后，该集合都会动态更新。 唯一微妙的部分是确保我们始终在打印后刷新，因为交互取决于立即同步。 

该逻辑没有显式模拟 Bob 的最优策略，因为贪婪不变量确保 Bob 的删除不会永久破坏前缀增长过程。

 ## 边缘情况

 当初始集合已经包含从 0 开始的长连续前缀时，就会出现关键边缘情况。在这种情况下，算法会立即设置`cur`超出该前缀并开始插入更大的值。 Bob 的删除只会影响前缀以上的元素，因此 MEX 很快就会稳定下来。 该策略仍然有效，因为没有发生不正确的早期推进。 

另一种情况是最初缺少 0。 这里`cur`从 0 开始，算法反复尝试插入它。 尽管鲍勃可以在允许的情况下删除它，但他无法阻止爱丽丝在后续移动中重新引入它，因此最终 0 在集合中稳定足够长的时间以前进`cur`至 1。 

最后，当集合包含非常大的间隙时，Bob 删除元素的能力与 MEX 形成无关，因为只有最小的缺失前缀才重要。 该算法自然会忽略这些大值，因为`cur`永远不会跳过缺失的整数。
