 ## 解决方案
 ## 问题理解

 我们从一棵有根的树开始$G$在$n$顶点，以顶点为根$1$。 对于每个顶点$v$，我们看“子树$v$” 定义为从根开始的路径经过的所有顶点$v$。 换句话说，它正是$v$， 包括$v$本身，以及它们之间的所有边缘。 因此每个顶点贡献一棵有根子树。 

我们将所有这些有根子树收集到一个多重集中$P(G)$。 如果两个子树的根树结构在保留根的同时重新标记顶点时相同，则认为它们是相同的。 

现在的任务是对抗性建设。 我们得到了原始树$G$，但我们没有被要求修改它。 相反，我们必须构建一个全新的有根树$G'$在相同数量的顶点上。 目标是制作尽可能少的子树$G'$匹配出现在的任何子树$P(G)$尽可能。 

因此，问题是在非常强的同构概念下避免两棵树之间的根子树的结构相似性。 

约束条件$n \le 10^6$立即排除任何显式比较子树形状或计算两棵树的所有有根子树的规范哈希的解决方案。 任何接触每对顶点或存储完整子树结构的方法都是不可能的。 我们需要一些线性或近线性的东西。 

一个微妙的点是，比较不是在单个树之间进行，而是在所有有根子树的多重集之间进行比较。 即使只有一个子树形状重复，它也会贡献多个匹配。 一个天真的误解是认为我们只比较整棵树； 相反，每个顶点都贡献一个结构。 

另一个常见的陷阱是假设子树同构需要 DP 哈希。 这意味着$O(n \log n)$或者每棵树更糟，这里速度太慢了。 

## 方法

 一种强力方法是计算每个有根子树的规范表示$G$，例如对已排序的子项使用 DFS 哈希，然后尝试构造$G'$并反复检查候选子树是否出现在原始多重集中。 即使我们乐观地假设散列在线性时间内工作，我们仍然需要推理所有可能的树$G'$，这是指数级的。 这已经表明搜索空间是完全难以处理的。 

真正的转折点是注意到什么实际上决定了有根树的结构直至同构。 有根树的特征完全在于其子树形状的多重集。 这意味着如果我们想避免匹配子树形状$G$，我们应该避免创建任何类似于中的“复杂分支模式”$G$。 

关键的观察是原始树的贡献最多$n$不同的有根子树形状，但大多数来自分支。 如果我们构建$G'$作为一个简单的结构，特别是一个长链，那么每个子树$G'$也是一条链。 所以$P(G')$仅包含类似路径的有根树。 

现在考虑任意树中存在哪些类型的子树$G$。 任何不是路径的子树都包含分支顶点。 所以如果我们确保$G'$根本没有分支，我们立即消除与所有非路径子树的匹配$G$。 唯一可能的匹配是路径子树$G$，而且这些都比较有限。 

在所有树木中$n$节点，路径最小化结构多样性。 路径的任何有根子树本身就是一条路径，由其大小唯一确定。 所以$G'$折叠多重集$P(G')$只进入$n$可能的路径长度。 

这给了我们一个建设性的解决方案：构建$G'$作为根于的单链$1$。 无需检查$G$根本不。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子树比较 | 指数| 大| 太慢了 |
 | 构建路径树 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 从顶点开始$1$，这将是新树的根$G'$。 我们选择它作为链的一个端点来维护有效的根结构。 
2. 创建顶点序列$1, 2, 3, \dots, n$。 该序列将定义一条简单的路径。 
3. 连接各个$i$到$i+1$为所有人$1 \le i < n$。 这形成了覆盖所有顶点的单链。 
4. 将这些边输出为树$G'$。 

选择每个步骤以确保不引入分支。 构造有意最小化：任何额外的边都会立即创建一个度数至少为 3 的节点或形成一个循环，这两者都会增加子树的复杂性和风险匹配结构$G$。 

### 为什么它有效

 不变量是在处理完第一个之后$k$顶点，构造的图是这些顶点上的单个路径。 这保证了每个子树$G'$由其大小唯一确定，并且本身就是一条路径。 

由于路径的每个子树又是一条路径，因此多重集$P(G')$仅包含路径形状的有根树。 的任意子树$G$这不是一个路径，不能匹配任何子树$P(G')$。 偶数路径子树$G$数量有限，不能超过$n$，因此这种结构通过破坏结构多样性来最小化重叠$G'$尽可能小的家庭。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    # read and ignore original tree
    for _ in range(n - 1):
        input()
    
    # build a simple path
    for i in range(1, n):
        print(i, i + 1)

if __name__ == "__main__":
    main()
```解决方案在读取后故意忽略输入树结构$n$。 原因是最优构造根本不依赖于原始树。 

循环构造边$i \rightarrow i+1$保证连通的无环图。 由于正好有$n-1$边和所有顶点都连接成链，结果是一棵有效的树。 

一个微妙的实现细节是快速 I/O。 即使我们只输出$n-1$行、读$n-1$边缘对于有效地消耗输入是必要的。

3 4

```施工：

 | 步骤| 行动| 当前边缘 |

 | 3 | 添加 3 | (1,2),(2,3) | (1,2),(2,3) |

```这显示了输入树中的所有分支是如何被完全丢弃的。 

跟踪确认在每一步结构都保持单个路径，确保不会出现子树分支模式。

 ## 边缘情况

 对于$n=2$，算法只是输出唯一可能的边缘$1-2$。 构造循环的执行不会超出单次迭代，因此结果仍然有效。 

对于高度分支的输入，例如以星形为中心的星形$1$，输入边被忽略并替换为链。 尽管原始树最大化了分支，但输出完全消除了所有分支，确保了其中没有子树$G'$类似于那些在$P(G)$超越平凡的路径结构。 

对于已经是路径的输入，算法输出相同的路径，无论方向如何。 由于所有有效输出都是树$n$顶点和路径始终有效，即使输入已经具有最小结构，构造也保持正确。
