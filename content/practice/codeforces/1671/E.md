 ## 解决方案
 ## 问题理解

 给定一个完全二叉树，大小为$2^n - 1$，其中每个内部节点恰好有两个子节点，并且所有叶子节点都位于同一级别。 每个节点都带有一个标签，要么是 A，要么是 B。结构是固定的，但在读取前序遍历字符串之前，我们可以任意次数地自由交换任何内部节点的左子节点和右子节点。 

节点的前序串是通过首先取节点自身的字符、然后是其左子树的前序串、然后是其右子树的先序串来形成的。 由于交换子树会改变子树的相对顺序，因此不同的交换选择可能会在根处产生不同的最终预序字符串。 任务是计算可能有多少个不同的根预序字符串。 

约束条件$n \le 18$意味着树最多有$2^{18} - 1 \approx 2.6 \cdot 10^5$节点。 任何尝试显式枚举交换选择的解决方案都是不可能的，因为有$2^{(2^n-1)/2}$可能的交换配置是天文数字。 该解决方案必须积极压缩子树信息，重用重复的结构。 

一个微妙的失败案例来自假设子树相等仅由结构或仅由字符确定。 两个不同的子树可能具有相同的字母集，但由于排序仍会产生不同的预排序字符串。 相反，两个形状不同的子树在交换后仍然可以生成相同的可能字符串集。 在不考虑交换自由度的情况下对原始前序字符串进行简单的散列将错误地将等效子树视为不同的。 

另一个陷阱是假设独立性：将左子树和右子树的计数相乘会忽略交换可能导致结果字符串集重叠的情况，特别是当两个子树的可能表示相同时。 

## 方法

 强力解决方案将为每个子树递归生成所有前序字符串，并在每个内部节点以两种可能的顺序连接左子树字符串和右子树字符串的所有组合。 这在概念上是正确的，因为它直接遵循定义：每个交换选择都会排列子树顺序，并且一旦顺序固定，预序构造就是确定性的。 

然而，每个节点可能的字符串数量可以呈指数增长。 在最底层，每个叶子会产生 1 个字符串，但上面的一层已经产生 2 个组合，并且这种增长会以倍数方式复合。 即使对于小$n$，不同字符串的数量变得难以管理，并且字符串连接本身变得过于昂贵。 

关键的观察是我们实际上不需要构造字符串。 我们只需要计算不同的结果。 该结构是完美二叉树，因此相同深度的每个子树具有相同的形状。 唯一的差异来自标签和交换选择。 

我们为每个节点定义它可以生成的字符串集的规范表示。 我们没有存储完整的集合，而是通过类似散列的结构和不同排列的计数对其进行编码。 关键的见解是，子树是由其两个子树的表示决定的，交换只会改变相同组合对象之间的顺序。 

我们将每个子树视为可能的子树编码的多重集。 如果左子树和右子树具有相同的编码集，则交换不会产生新的配置。 如果它们不同，则交换会使该节点级别的结构选择数量增加一倍，但生成的字符串集仍然对称组合。 

因此，在每个节点，我们计算：

 - 其子树的结构签名，
 - 以及它可以生成的不同预序字符串的数量。 

我们通过孩子的签名来比较他们。 如果相等，交换不会产生新的结果。 如果不同，左右顺序很重要，但我们仍然只需要考虑两个方向一次。 

这将问题简化为树上自下而上的 DP。

 | 暴力破解（字符串枚举）| 节点指数 | 指数| 太慢了|

 ## 算法演练

 我们从叶子向上按后序处理树。 

1. 为每个叶子分配一个由其标签组成的基本表示。 它可能的字符串数量为 1，其签名源自字符。 
2. 对于每个内部节点，首先计算其左子节点和右子节点的表示。 这确保我们始终组合已经计算的子树信息。 
3. 比较两个儿童签名。 如果它们相同，则交换不会改变任何内容，因此不同字符串的数量很简单：$$dp[x] = dp[left] \cdot dp[right]$$4. 如果签名不同，则交换产生第二种排列。 然而，两个方向都会产生有效的预序结构，因此：$$dp[x] = 2 \cdot dp[left] \cdot dp[right]$$但我们必须确保我们不会重复计算结构相同的结果。 这是通过将有序签名对合并到规范形式中来处理的。 
5. 节点的签名定义为：$$(s_x, \min(sig_L, sig_R), \max(sig_L, sig_R))$$其中排序是按子签名的字典顺序排列的。 这确保了当子项相同或不同时，交换产生相同的签名表示，而不会产生歧义。 
6. 继续此过程直至根。 答案是根部的 dp 值取模$998244353$。 

### 为什么它有效

 关键的不变量是，对于每个节点，其计算出的签名唯一地表示可通过交换后代获得的所有子树配置的等价类。 任何两个具有相同签名的子树都会生成完全相同的一组前序字符串。 因为一旦子签名固定，每个子树决策都是本地且独立的，因此乘法组合计数是有效的。 签名中的规范排序可防止纯粹由左右对称引起的重复计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

n = int(input())
s = input().strip()

# Build tree implicitly; nodes are 1-indexed
# dp[x] = number of distinct preorder strings from subtree x
# sig[x] = canonical hash-like representation

sys.setrecursionlimit(10**7)

dp = [0] * (2**n)
sig = [None] * (2**n)

# We will use a tuple as a hashable signature
# (char, left_sig, right_sig) with ordered children

def dfs(x):
    if x >= 2**n:
        return

    left = 2 * x
    right = 2 * x + 1

    if left >= 2**n:
        sig[x] = s[x-1]
        dp[x] = 1
        return

    dfs(left)
    dfs(right)

    sl = sig[left]
    sr = sig[right]

    # canonical ordering
    if sl <= sr:
        sig[x] = (s[x-1], sl, sr)
    else:
        sig[x] = (s[x-1], sr, sl)

    if sl == sr:
        dp[x] = (dp[left] * dp[right]) % MOD
    else:
        dp[x] = (2 * dp[left] * dp[right]) % MOD

dfs(1)
print(dp[1] % MOD)
```该实现依赖于用一个元组来表示每个子树，该元组捕获其根标签及其子树的规范排序。 这避免了构建实际的字符串。 子签名之间的比较确保我们检测对称性：当两个子签名相同时，交换不会产生新的不同的预序字符串。 

DFS 在处理父母之前处理孩子，保证每个 dp 值在需要时准备就绪。 乘法结合了子树的独立选择，而可选因子 2 仅在交换导致真正不同的排列时出现。 

一个微妙的点是我们从不存储完整的字符串； 元组表示就足够了，因为这些元组的相等性恰好对应于它们所表示的预序字符串集合的相等性。

| 节点| 左信号 | 右签名| 平等| DP |

 ## 边缘情况

 所有标签都相同的完全统一的树是朴素方法最明显的失败点。 在这种情况下，每个级别的每个子树都具有相同的结构和相同的签名。 该算法在每次合并时都会重复识别相等性，因此 dp 值一直到根都保持为 1。 任何在每个节点乘以 2 的尝试都会错误地爆炸为$2^{2^n-1}$，这是错误的，因为所有交换都保留相同的前序字符串。 

第二种边缘情况是左子树和右子树仅在更深层次的结构上不同，但产生相同的签名。 规范元组比较确保它们在父级处被视为相等，从而防止由于不影响预序输出等价性的结构不对称而导致的过度计数。
