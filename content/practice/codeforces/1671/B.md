 ## 解决方案
 ## 问题理解

 我们在数轴上得到一组点，这些点已经按升序排列。 每个点最多允许“摆动”一个单位，这意味着它的最终位置可以是它的原始坐标，向左一步或向右一步。 

在所有移动之后，我们希望这些点占据一个完美填充的整数段，没有间隙，也没有重叠。 换句话说，如果有$n$点，它们的最终位置必须恰好是一些连续的整数$l, l+1, \dots, l+n-1$。 

任务是决定是否对其范围内的每个点进行这样的重新分配$[-1, 0, +1]$灵活性范围可以产生连续的块。 

约束很严格：所有测试用例的总点数达到$2 \cdot 10^5$，因此任何试图探索所有运动组合的解决方案都是立即不可行的。 每个点都有 3 个独立的选择，因此暴力状态空间的增长为$3^n$，这远远超出了任何计算极限。 

一个更微妙的约束是输入是排序的。 这种结构很重要，因为它允许我们按顺序推理分配，而不是将点视为独立的对象。 

天真的贪婪推理往往会忽略一些失败案例。 一个是假设我们总是可以贪婪地将每个点分配给最近的可用整数槽而不需要回溯。 例如，如果点间隔不均匀，例如`1 2 3 7`，贪婪分配可能会过早地消耗 1-3 附近的槽位，并且即使存在有效的移位，也不会为 7 留下有效的位置，反之亦然，具体取决于排序选择。 另一个陷阱是忘记移动既可以增加也可以减少间隙，因此仅推理原始间隙是不够的。 最后，最终位置必须不同的要求意味着我们不能将两个点分配给同一个整数，即使两个点都被允许单独落在那里。 

## 方法

 强力解释将为每个点分配三个值之一，然后检查结果集是否形成连续的整数序列。 这是正确的但不可行，因为它探索了$3^n$每个测试用例的配置。 即使是为了$n = 30$，这已经是一个天文数字了。 

关键的观察是，我们想要的最终结构非常刚性：一旦我们固定了起始位置$l$，每个点都有一个由其索引确定的目标槽。 我们可以考虑将排序的点与理想的连续模板相匹配，而不是考虑点移动的位置。 

由于最终的数组是严格递增的并且没有间隙，因此如果我们对最终选择的位置进行排序，它们必须与移位的身份序列完全匹配。 这允许贪婪的对齐策略：我们尝试将每个输入点按顺序分配给假设段中的目标位置。 

关键的简化是将其视为每个点和目标索引之间的匹配问题，确保每个分配都在$[x_i - 1, x_i + 1]$。 因为两个序列都是有序的，所以我们可以贪婪地从左到右对齐并检查可行性，而无需回溯。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(3^n)$|$O(n)$| 太慢了|
 | 贪心匹配|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们尝试从不同的可行偏移量开始构造最终段，但我们没有明确枚举它们。 相反，我们直接模拟将每个点分配给连续的整数槽。 

1. 我们假设最后一段以某个值开始$l$，而不是修复$l$，我们在概念上将第一个点与其范围内的可行槽对齐。 这消除了明确猜测的需要$l$。 
2. 我们按升序处理点并维护仍可分配的最小可用整数。 对于$i$第-点，预期的插槽是$i$- 依赖于连续序列。 
3. 对于每个点$x_i$，我们考虑当前所需的位置$pos$。 如果$pos$位于内$[x_i - 1, x_i + 1]$, 网络分配$x_i$到$pos$。 这是唯一明智的任务，因为延迟或提前只会降低未来的灵活性。 
4.如果$pos < x_i - 1$，我们增加$pos$到$x_i - 1$。 这确保了我们不会尝试将点放置在其所能到达的位置的左侧太远。 
5. 如果$pos > x_i + 1$，我们立即失败，因为当前点无法到达连续结构中任何剩余的有效槽。 
6. 将位置分配给一个点后，我们递增$pos$并继续。 

如果我们能够成功分配所有分数，那么最终的答案是“是”。 

### 为什么它有效

 该算法在假设的连续序列中维护运行的“下一个所需时隙”。 在每一步中，我们要么将当前点与该槽对齐，要么向前移动槽以保持在可行性范围内。 关键的不变量是处理后$i$第一点，我们构造了一个有效的部分连续段，并确保所有处理过的点都可以嵌入到扩展此前缀的某个有效的最终段中。 由于输入和目标结构都是单调的，因此任何局部故障（无法到达其所需槽位的点）都无法在不破坏早期分配的情况下在以后修复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        x = list(map(int, input().split()))

        pos = -10**18
        ok = True

        for i in range(n):
            # desired slot for i-th element in consecutive segment
            if pos < x[i] - 1:
                pos = x[i] - 1

            if pos > x[i] + 1:
                ok = False
                break

            pos += 1

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```解决方案保留一个指针`pos`代表我们想要在最后一个连续段中占据的下一个整数。 对于每个点，如果该指针太小而不可行，我们就向上调整该指针。 如果它超过了该点的最大可到达位置，则配置将变得不可能。 

增量`pos += 1`这是至关重要的，因为一旦分配了一个槽，下一个点必须占据段中的下一个整数。 一个微妙的细节正在初始化`pos`到一个非常小的值，因此第一个点可以在其允许的范围内自由选择其位置。

 ## 边缘情况

 最小单元素输入总是成功的，因为任何点都可以移动以形成长度为 1 的线段。 算法初始化`pos`足够低，第一次检查总是成功，并且循环分配唯一的槽而不会发生冲突。 

像这样的案例`1 10 11`演示了失败，其中第一个大间隙迫使所需位置太靠前，最终超出了最后一个点的可到达范围。 在执行过程中，`pos`超越`x[i] + 1`对于第一个无法弥补差距的元素，立即触发拒绝。 

紧密排列的序列，例如`2 5 6`显示了算法如何在允许的范围内自然地向上“拉伸”较早的点，将它们对齐到有效的连续段中，而无需显式回溯。
