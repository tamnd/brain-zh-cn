 ## 解决方案
 ## 问题理解

 我们给出了一个圆形排列$m$座位和名单$n$人们。 每个人都有自己的“排除半径”$a_i$：如果他们坐在某个座位上，则选择最近的座位$a_i$圆圈两侧的座位必须保持空位。 换句话说，每个人不只是占据一张椅子，他们有效地阻挡了一个连续的弧线$2a_i + 1$圆圈上的座位，以其位置为中心。 

任务是决定我们是否可以将所有人都放在圆圈上，以便这些被封锁的区域不会重叠。 

重要的结构细节是，这纯粹是关于圆上的填充间隔，其中每个间隔都有长度$2a_i + 1$，并且区间必须不相交。 

这些限制使得暴力放置变得不可能。 所有测试用例的总人数最多为$10^5$，而椅子的数量可以大到$10^9$。 任何试图单独模拟座位或检查位置的方法都会立即被排除。 甚至$O(n^2)$每个测试用例都会太慢。 

一个微妙的边缘情况是当总需求接近圆圈大小时。 例如，如果$m = 5$和所有$a_i = 2$，那么每个人挡5个座位，也就是说最多只能坐一个人。 忽略圆形环绕的贪婪方法可能会错误地假设线性间距有效，但环绕会导致最后一个和第一个放置之间发生重叠。 

另一个棘手的情况是当许多小$a_i$价值观与单一的大价值观共存。 大值会占据并消耗大部分可用空间，即使较小的值看起来很灵活，也不会留下有效的排列。 

## 方法

 一个直接的暴力想法是模拟圆圈上的座位位置。 我们可以尝试将每个人安排在一些可用的座位上，并标记出阻塞的时间间隔。 这将涉及维护空闲段的结构并在检查重叠时重复插入间隔。 在最坏的情况下，每个放置都可能需要扫描几乎所有剩余空间，从而导致$O(nm)$如果天真地做出这样的行为，这是不可能的$m$最多$10^9$。 

关键的观察是个人立场根本不重要。 只有占用和阻塞的空间总量才重要。 每个人的消费量都是准确的$2a_i + 1$圈子的席位，并且这些消费不得重叠。 由于圆没有边界，我们可以将其视为总容量问题：我们试图打包总长度不得超过的线段$m$。 

因此，问题简化为检查是否：$$\sum (2a_i + 1) \leq m$$然而，这在循环设置中有点误导，因为邻接约束不允许任意打包顺序来帮助减少空间。 正确的细化是仅通过求和隐式地按大小排序，因为所有段都是刚性的并且不能重叠或压缩。 

所以可行性条件纯粹是一个总和检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟 |$O(nm)$|$O(m)$| 太慢了|
 | 占用长度总和|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 对于每个人，计算他们有效占据的座位数，即$2a_i + 1$。 这代表他们的座位加上两侧所需的空缓冲区。 
2. 将所有人的这些值相加，得到所需的总空间。 
3. 将这个总数与$m$，圆的大小。 
4. 如果所需总空间小于或等于$m$，输出“是”。 否则输出“NO”。 

求和背后的原因是，每个人的禁区一定是不相交的，并且每个区域都有固定的长度，无论位置如何。 

### 为什么它有效

 每个人都会产生一个连续的座位块，这些座位不能与任何其他块重叠。 由于这些块是刚性且独立的，因此任何有效的配置都对应于将圆划分为这些精确长度的不相交线段。 该圈有总容量$m$，所以必要条件是段长度之和不超过$m$。 这也是足够的，因为如果总长度合适，我们总是可以将线段按顺序放置在圆周围，而间隙不会小于所需的间隔，并且环绕不会引入超出总容量的新约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        
        total = 0
        for x in a:
            total += 2 * x + 1
        
        if total <= m:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```该实现是派生条件的直接转换。 每个$a_i$扩展到其完全占用的段长度$2a_i + 1$，并累积成连续总和。 最终对比$m$决定可行性。 

这里一个常见的错误是忘记了中间的座位$2a_i + 1$，仅使用$2a_i$，这会低估总使用量并导致错误的“YES”输出。

 ## 边缘情况

 一个关键的边缘情况是当$n = 1$。 该公式简化为检查是否$2a_1 + 1 \leq m$。 例如，如果$m = 3$和$a_1 = 1$，该人恰好占据了所有 3 个座位，这是有效的。 该算法正确地将总计计算为 3 并返回 YES。 

另一个边缘情况是当所有$a_i = 1$。 每人占3个座位。 如果$m = 8$和$n = 3$，总数变为 9，这超出了容量，即使在视觉上人们可能试图用环绕来“适应”它们。 该算法正确地拒绝了它，因为当总需求超过供给时，无法避免循环重叠。 

最后一个边缘情况是$m$很大但是$n$很小。 例如，$n = 2$,$m = 10^9$,$a = [10^9, 10^9]$。 总和变为$4 \cdot 10^9 + 2$，立即超过$m$，无需任何几何推理即可正确生成 NO。
