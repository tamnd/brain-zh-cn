 ## 解决方案
 ## 问题理解

 我们有一份学生名单，每个学生都有一个编程技能分数。 任务是组建尽可能最大的团队，使得技能最高和技能最低的成员之间的差异不超过 5。换句话说，对于任何规模的团队$k$，如果技能是$s_1, s_2, ..., s_k$， 然后$\max(s_i) - \min(s_i) \le 5$。 我们的目标是确定这样一个团队的最大规模。 

输入包括$n$，学生人数，其次是$n$代表技能水平的整数。 输出是一个整数：最大的平衡团队规模。 约束条件告诉我们$n$可以达到$2 \cdot 10^5$技能水平可以大到$10^9$。 这意味着天真$O(n^2)$检查每个可能的学生组的方法需要最多$4 \cdot 10^{10}$在最坏的情况下，操作速度太慢了。 我们需要一些更接近线性或$O(n \log n)$以适应 2 秒的限制。 

当所有学生都具有相同的技能水平时，就会出现边缘情况。 任何分组都是有效的，所以答案应该是$n$。 另一个边缘情况是每个学生的技能与下一个最接近的学生的技能相差超过 5 个； 在这里，最大的平衡团队只有一名成员。 粗心的方法可能会忘记处理这个问题，并假设每个团队至少有两名学生，从而产生错误的结果。 

## 方法

 蛮力方法将迭代每个可能的学生子集，计算每个子集的最大和最小技能，并检查它们的差异是否最多为 5。满足此条件的最大大小的子集将是答案。 这是正确的，因为它详尽地检查了所有有效的团队，但对于大型团队来说却失败了$n$由于组合爆炸，有$2^n$子集。 

优化的关键在于，一旦我们按技能对学生进行排序，学生的顺序就不再重要了。 如果数组已排序，则任何平衡组都必须对应一个连续的子数组，其中第一个元素和最后一个元素之间的差异最多为 5。这使我们能够将问题简化为滑动窗口或两指针技术。 我们扩展右侧指针以包含尽可能多的学生，直到差值超过 5，然后向前移动左侧指针以恢复平衡。 排序后的线性扫描保证了我们有效地检查每个潜在的团队。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 太慢了 |
 | 排序数组上的两指针 | O(n log n) | O(n log n) | O(1) 额外 | 已接受 |

 ## 算法演练

 1.读取学生人数$n$以及他们的技能水平到一个数组中。 对它们进行排序可以轻松检查连续的组。 
2. 按升序对技能级别进行排序。 排序后，任意平衡队对应一个首尾元素最多相差5的子数组。 
3.初始化两个指针，`left`和`right`，都从排序数组的开头开始。 同时初始化`max_team`为 0 以存储找到的最大团队规模。 
4. 展开`right`指针向前。 对于每个位置`right`，检查之间的差异`skills[right]`和`skills[left]`。 如果差值超过5，则增加`left`直到差异再次达到最多 5。 这保持了窗口的不变性`[left, right]`始终是一个平衡的团队。 
5. 更新`max_team`与当前窗口的大小，`right - left + 1`，如果它大于先前的最大值。 
6. 继续此过程直到`right`到达数组末尾。 打印`max_team`。 

工作原理：由于数组已排序，任何包含差异大于 5 的元素的子数组都无法在不违反平衡约束的情况下进行扩展。 滑动左指针可确保我们始终保持最大可能的窗口结束于`right`即满足条件。 不会错过任何平衡的团队，因为每个潜在的连续子数组都被恰好考虑一次`right`进步。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
skills = list(map(int, input().split()))

skills.sort()
max_team = 0
left = 0

for right in range(n):
    while skills[right] - skills[left] > 5:
        left += 1
    max_team = max(max_team, right - left + 1)

print(max_team)
```代码首先读取技能级别并对其进行排序。 两分球循环确保我们始终保持球队的平衡。 while 循环前进`left`仅当差异超过 5 时，这很微妙，但对于避免差一错误至关重要。 更新中`max_team`调整后`left`确保记录最大的窗口。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log n) | O(n log n) | 排序占主导地位。 两指针扫描的时间复杂度为 O(n)，因为每个指针最多移动 n 次。 |
 | 空间| O(n) | 存储技能数组。 排序可以就地完成，无需额外的内存。 |

 这非常符合约束条件：$n = 2 \cdot 10^5$，排序大约需要$4 \cdot 10^6$操作，两分球传球又增加了一个$2 \cdot 10^5$，轻松地不到 2 秒。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    skills = list(map(int, input().split()))
    skills.sort()
    max_team = 0
    left = 0
    for right in range(n):
        while skills[right] - skills[left] > 5:
            left += 1
        max_team = max(max_team, right - left + 1)
    return str(max_team)

# Provided samples
assert run("6\n1 10 17 12 15 2\n") == "3"
assert run("5\n5 5 5 5 5\n") == "5"
assert run("1\n100\n") == "1"

# Custom cases
assert run("3\n1 7 13\n") == "1"  # no pair within 5
assert run("4\n1 2 3 7\n") == "3"  # first three form a team
assert run("5\n1 2 3 4 6\n") == "4"  # largest balanced team [1,2,3,4]
assert run("2\n1 6\n") == "2"  # boundary case exactly 5 apart

 ## 边缘情况

 对于单身学生的情况`1\n100`，算法初始化`left`和`right`为 0 时，计算`window size = 1`，并返回 1。没有 while 循环触发，因此它可以正确处理最小尺寸输入。
