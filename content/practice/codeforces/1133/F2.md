 ## 解决方案
 ## 问题理解

 我们得到一个连接的无向简单图，并要求仅使用现有的边构建生成树。 附加约束是顶点 1 在所选树中的度数必须恰好为 D。 

生成树是边的子集，它无环地连接所有顶点，并且恰好包含 n − 1 条边。 额外的限制将问题从“查找任意生成树”更改为“查找顶点 1 在树内具有规定数量的邻居的生成树”。 

大小限制允许最多 200,000 个顶点和边。 这立即排除了尝试所有生成树或通过重新计算一一删除边的任何方法。 每次测试超出线性或近线性时间的任何时间都会太慢，因此解决方案必须围绕单个图遍历构建，并进行少量簿记，通常为 O(n + m)。 

有几种情况可能会导致天真的推理失败：

 如果顶点 1 在原始图中的邻居数少于 D 个，则答案是不可能的，因为它在任何生成树中的度都不能超过其在原始图中的度。 例如，如果 1 仅连接到两个节点，但 D = 3，则任何构造都无法满足要求。 

如果我们贪婪地构建一棵生成树，然后简单地尝试“调整”顶点 1 的度数，我们可能会创建循环或断开组件。 例如，当我们需要 2 度时，DFS 树可能会给出顶点 1 度 5，并且删除与 1 相关的任意边可以断开树的各个部分。 

正确的方法必须控制哪些与顶点 1 相关的边进入生成树，同时仍确保连通性。 

## 方法

 一种暴力的视角是枚举生成树，或者在强制度数限制的同时模拟构建生成树。 即使是像尝试与顶点 1 相关的每个边子集并检查它是否可以扩展到完整生成树这样的温和变体也会导致指数行为，因为每个选择都会改变全局的连接性。 

关键的观察是我们不需要自由决定整个树结构。 相反，我们可以首先决定顶点 1 的哪些邻居将成为其树子节点，然后以标准方式完成树的其余部分。 

实现这一点的结构是基于 DSU 的生成森林构造，并结合从顶点 1 贪婪选择边。其想法是首先忽略与 1 相关的所有边，并在顶点 2 到 n 之间构建生成森林。 然后，我们有选择地将顶点 1 连接到恰好 D 个不同的组件，确保每个选定的连接合并组件而不形成循环。 

这是可行的，因为每个生成树都可以被视为首先在顶点 {2..n} 上形成森林，然后附加顶点 1 以连接所有组件。 顶点 1 的度数正是它所连接的组件的数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力枚举| 指数| O(n) | 太慢了 |
 | DSU + 贪婪附件 | O(m α(n)) | O(m α(n)) | O(n + m) | 已接受 |

 ## 算法演练

 我们分两个阶段构建生成树。 

首先，我们忽略与顶点 1 相关的所有边，并在顶点 2 到 n 上构建 DSU 结构。 对于端点都不为 1 的每条边 (u, v)，如果它们属于不同的组件，我们会将此边添加到树中并将它们合并。 这会产生一个超过 {2..n} 的生成森林。 

此时，图可能仍具有多个组件。 每个组件最终都需要通过一条选定的边连接到顶点 1。

其次，我们处理与顶点 1 相关的所有边。对于每个这样的边 (1, v)，我们检查 v 是否属于尚未连接到 1 的组件。如果是，我们使用该边将顶点 1 连接到该组件，并将其与代表顶点 1 的特殊 DSU 联合。 

我们必须确保我们使用的正是 D 个这样的边。 如果我们最终得到的可用组件少于 D 个，我们就无法达到所需的程度。 如果我们有更多，一旦选择了 D 边，我们就提前停止，但我们必须确保剩余的图仍然是连通的。 这是通过优先考虑连接不同组件的边缘来处理的。 

最后，在使用来自顶点1的D条边之后，我们仍然需要确保所有顶点都是连接的。 如果多个分量与 1 或彼此之间保持断开连接，则仅当它们不违反度数约束时，我们才使用与 1 相关的剩余边； 否则无法施工。 

查看该过程的更清晰的方法是：

 我们将 1 的每个邻居视为组件的潜在连接器。 我们必须精确地选择其中的 D 个，以便在将每个选定的邻居收缩为 1 后，所有剩余的顶点形成一个连接的结构。 

DSU 确保我们永远不会在森林内形成超过 {2..n} 的循环，并且我们只使用连接不同组件的边。 

### 为什么它有效

 每个生成树都可以以顶点 1 为根。在这样的有根树中，1 的子节点对应于删除 1 后形成的不同组件。因此，顶点 1 的度等于删除它而在森林中产生的组件数。 我们的构造显式地在 {2..n} 上创建一个森林，然后将这些组件中的 D 个精确地附加到顶点 1。由于 DSU 确保每个组件内部的非循环性，并且我们仅在必要时连接组件，因此生成的结构是连接的且非循环的，因此是有效的生成树。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

def solve():
    n, m, D = map(int, input().split())
    edges = []
    star = []
    
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        if u == 0 or v == 0:
            star.append((u, v))
        else:
            edges.append((u, v))

    dsu = DSU(n)
    tree = []

    for u, v in edges:
        if dsu.union(u, v):
            tree.append((u, v))

    comp_set = set()
    for u, v in star:
        comp_set.add(dsu.find(v if u == 0 else u))

    used = 0
    used_edges = []

    for u, v in star:
        if used == D:
            break
        x = v if u == 0 else u
        if dsu.union(0, x):
            used_edges.append((u, v))
            used += 1

    if used != D:
        print("NO")
        return

    # connect remaining components if needed using leftover star edges
    for u, v in star:
        if dsu.union(u, v):
            tree.append((u, v))

    if len(tree) != n - 1:
        print("NO")
        return

    print("YES")
    for u, v in tree:
        print(u + 1, v + 1)

if __name__ == "__main__":
    solve()
```该代码将边分为与顶点 1 相关的边和所有其他边。 DSU 首先在非 1 顶点上构建一个生成森林，确保我们永远不会在那里创建循环。 然后，我们使用最多 D 条边选择性地附加顶点 1，这些边连接之前单独的组件。 

关键的实现细节是，每次我们使用与 1 相关的边时，我们立即将其端点合并到包含 1 的组件中，确保我们永远不会重复使用它来形成循环。 最终检查确保恰好选择了 n − 1 条边，这证实了我们构建了生成树。

 输入：```
4 5 1

```我们首先在节点 2、3、4 上构建 DSU。 

| 步骤| 边缘 | DSU 行动 | 树边| 学位(1) |
 | ---| ---| ---| ---| ---|
 | 1 | 2-3 | 2-3 联盟| 2-3 | 2-3 0 |
 | 2 | 3-4 | 3-4 联盟| 2-3, 3-4 | 2-3, 3-4 | 0 |

 现在我们从 1 开始处理边。我们需要 D = 1 条边。 

我们选择 1-2（或任何连接新组件的有效选项）。 

| 步骤| 边缘 | DSU 行动 | 树边| 学位(1) |
 | ---| ---| ---| ---| ---|
 | 3 | 1-2 | 1-2 连接 | +1-2 | 1 |

 最终的树已连接，并且顶点 1 的度数恰好为 1。 

这显示了 DSU 如何将问题简化为选择一个代表性连接。 

### 示例 2

 输入：```
5 5 2
1 2
1 3
2 4
3 5
4 5
```首先使用非 1 边在 {2,3,4,5} 上构建 DSU：

 | 步骤| 边缘 | 行动| 组件|
 | ---| ---| ---| ---|
 | 1 | 2-4 | 2-4 联盟| {2,4} {3} {5} |
 | 2 | 3-5 | 3-5 联盟| {2,4} {3,5} |
 | 3 | 4-5 | 联盟| 全部连接|

 现在只有一个组件存在，因此顶点 1 只能连接到一个组件。 由于 D = 2，我们不能满足约束，所以答案是否定的。 

这证明了关键的可行性条件：顶点 1 不能连接比现有组件更多的组件。

 ## 边缘情况

 一种重要的边缘情况是，除了 1 之外的所有顶点都已连接，而不使用 1 中的任何边。在这种情况下，顶点 1 只能附加到一个组件，因此任何大于 1 的 D 都会强制失败。 该算法处理此问题是因为非 1 个节点上的 DSU 生成单个组件，并且可用附件的数量恰好为 1。 

另一种情况是，顶点 1 恰好具有 D 个入射边，但其中一些连接已在同一组件中的顶点。 DSU 检查防止计算冗余边，因此我们只计算实际增加连接性的边，避免与树中的新结构不对应的膨胀度。 

最后一个微妙的情况是来自顶点 1 的多条边连接到同一个 DSU 组件。 只能使用第一个这样的边； 后面的会被忽略，因为它们不会改变 DSU 结构。 这确保度计数反映不同的结构附件而不是原始邻接。
