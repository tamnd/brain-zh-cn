 ## 解决方案
 ## 问题理解

 我们有一个由小写字母组成的密文字符串。 字符串中的每个字符都已移动相同的凯撒密码偏移量，但偏移量未知。 我们还得到了几个目标短语。 对密文应用正确的反向移位后，这些短语中的每一个都必须作为连续子串出现在某处。 

任务是找到任何可以将密文转换为包含所有给定短语的字符串的移位值。 输出是解码后的字符串，因此我们需要实际应用发现的移位并打印结果。 

密文长度最大为1000，短语最多为1000个。 每个短语都很短，长度最多为 30。这些限制足够小，我们可以尝试所有可能的凯撒变换。 凯撒密码只有 26 个可能的偏移量，因此主要工作是检查 26 个候选解码字符串。 由于字符串长度约为 1000 和 1000 个短语，即使是二次样式检查也仍远低于限制。 依赖于更大搜索空间的算法（例如尝试任意替换）不适合问题的结构。 

主要的边缘情况来自于错误地处理移位方向或假设仅检查一个短语就足够了。 例如，考虑：```
abc
1
b
```正确的解码字符串是：```
bcd
```因为移动了每个字母`abc`前进一位使该短语`b`出现。 总是向后移动的解决方案将会失败。 

另一种情况是当答案偏移为零时：```
hello
2
hell
llo
```输出应该是：```
hello
```假设需要一些非零运动的粗心实现将错过这个有效答案。 

最后一个微妙的情况是重复出现和重叠的短语：```
aaaa
2
aa
aaa
```正确的输出是：```
aaaa
```子字符串检查必须与重叠一起使用。 通过手动标记已使用的字符进行搜索将错误地拒绝这种情况。 

## 方法

 直接的方法是模拟每一个可能的凯撒转变。 由于只有 26 种可能的转换，我们可以为每一种转换整个字符串。 对于每个候选解码字符串，我们扫描所有短语并检查每个短语是否是子字符串。 如果每个短语都出现，我们就找到了有效的答案。 

这种蛮力是正确的，因为凯撒密码具有有限的可能性。 原始消息必须准确对应这 26 个轮班中的一个，因此测试所有这些轮班可以保证我们能够到达它。 

唯一可能的低效率来自于重复的子字符串检查。 在最坏的情况下，我们尝试 26 次移位，每次移位 1000 个短语，并且每次子字符串搜索大约需要密文的长度。 这提供了大约 26 * 1000 * 1000 次操作，这在高级估计中仅是大约 2600 万个基本字符比较。 对于给定的限制，这是完全可以接受的。 

关键的观察结果是密码空间很小。 我们不需要以数学方式恢复移位或构建高级字符串匹配结构。 未知值是 0 到 25 之间的一个数字，因此枚举是自然的解决方案。 该问题看起来像一个字符串问题，但较小的搜索空间决定了复杂性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(26 * n * m * l) | O(26 * n * m * l) | O(n) | 已接受 |
 | 最佳 | O(26 * n * m * l) | O(26 * n * m * l) | O(n) | 已接受 |

 这里，`n`是密文长度，`m`是短语的数量，并且`l`是最大短语长度。 

## 算法演练

 1. 阅读密文和所有必需的短语。 存储短语，因为必须针对每个可能的解码字符串测试相同的列表。 
2. 尝试从 0 到 25 的每个可能的凯撒移位。对于每个移位，通过将每个密文字符移动该数量来创建候选解码字符串。 
3. 根据候选字符串检查每个短语。 如果甚至缺少一个短语，请放弃此转变并继续。 
4. 当移位使所有短语出现时，立即打印解码后的字符串。 由于答案肯定存在，因此某些转变将会成功。 

这样做的原因是密文只有 26 种可能的解码版本。 正确的肯定会在其中，因此我们找到的第一个有效候选者就足够了。 

### 为什么它有效

 搜索的不变性是我们测试的每个候选字符串都是密文的有效凯撒变换。 我们永远不会跳过可能的解码字符串，因为会检查从 0 到 25 的每个移位值。 

为了正确转换，每个必需的短语必须出现在问题保证中。 检查阶段准确接受所有短语都存在的字符串，因此正确的移位将通过测试并返回。 在异常情况下，错误的移位也可能会通过，但任何有效的解码字符串都会被接受，因此返回第一个通过的候选就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = int(input())
    phrases = [input().strip() for _ in range(n)]

    length = len(s)

    for shift in range(26):
        decoded = []
        for ch in s:
            decoded.append(chr((ord(ch) - ord('a') + shift) % 26 + ord('a')))
        decoded = ''.join(decoded)

        ok = True
        for p in phrases:
            if p not in decoded:
                ok = False
                break

        if ok:
            print(decoded)
            return

if __name__ == "__main__":
    solve()
```该解决方案首先存储短语，因为它们需要为所有 26 个候选者重复使用。 重新计算或重新读取它们会增加不必要的工作。 

解码循环将每个字符转换为 0 到 25 之间的数字，通过模算术应用移位，然后将其转换回来。 模运算处理环绕情况，例如移位`z`转发至`a`。 

短语验证使用Python的子字符串搜索。 这是安全的，因为总输入大小很小。 缺少短语时的早期中断可以避免在候选失败后进行不必要的检查。 

该代码检查每个班次，包括零。 这很重要，因为密文可能已经是解码后的消息。

## 测试用例```python
import sys, io

def solve_case(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    s = input().strip()
    n = int(input())
    phrases = [input().strip() for _ in range(n)]

    for shift in range(26):
        decoded = ''.join(
            chr((ord(c) - ord('a') + shift) % 26 + ord('a'))
            for c in s
        )

        if all(p in decoded for p in phrases):
            return decoded + "\n"

    return ""

 ## 边缘情况

 对于零位移情况：```
hello
2
hell
llo
```该算法从shift 0开始，构建`hello`，并检查这两个短语。 由于两者都存在，因此它立即返回。 从班次 1 开始搜索的解决方案最终仍然有效，但检查零可以使推理简单并避免不必要的假设。 

对于环绕式情况：```
z
1
a
```在移位 1 时，字符计算变为`(25 + 1) % 26 = 0`，映射回`a`。 这就是模运算至关重要的原因。 

对于重叠匹配：```
aaaa
2
aa
aaa
```候选字符串在移位 0 处保持不变。子字符串检查发现`aa`和`aaa`在字符串的同一区域内。 该算法只关心存在性，而不关心消耗字符，因此自然会处理重叠。
