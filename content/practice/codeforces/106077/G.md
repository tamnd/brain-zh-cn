 ## 解决方案
 ## 问题理解

 我们得到了一系列探测器，每个探测器都有两个限制：它可以承受多少温度以及它可以承受多少风。 每个探头也有建造成本。 除此之外，我们还获得了天王星上的多个着陆点，每个着陆点都有温度和风力等级。 

对于每个着陆点，我们必须选择一个足够坚固的探测器，能够同时承受这两种条件，这意味着它的温度限制至少是现场温度，其风速限制至少是现场风速。 在所有这些有效的探测器中，我们想要最便宜的一个。 如果没有探测器满足这两个约束，则答案为-1。 

该结构是一个经典的二维支配过滤问题，其中每个探针都是二维能力空间中的一个点，每个查询都要求一个点支配阈值点，同时最小化成本。 

这些约束允许最多 100,000 个探测和 100,000 个查询，所有值最大为 10^9。 每个查询进行简单的二次比较是立即不可行的。 在最坏的情况下，即使对探针进行排序并扫描每个查询仍然会太慢。 我们需要一种预处理策略来减少跨查询的重复扫描。 

当多个探测器以不同方式主导查询时，就会出现微妙的边缘情况。 例如，一种探头可能具有极高的耐温性，但耐风性较弱，而另一种探头则相反。 仅按一维排序并选择最小成本的幼稚方法可能会失败。 

考虑：

 输入：

 n = 2

 探头：

 (10, 1, 成本 5)

 (1, 10, 成本 5)

 查询：

 (5, 5)

 两种探测器都在一个维度上占主导地位，但在另一个维度上却失败了。 正确的输出是-1。 在修剪过程中按温度排序并忽略风力限制的简单解决方案可能会错误地返回成本 5。 

另一个陷阱是假设单调增加一个属性可以保持可行性。 具有较高耐温性的探头并不能保证更好的耐风性，因此我们无法在没有额外结构的情况下将问题简化为单个排序扫描。 

## 方法

 暴力破解的想法很简单：对于每个查询，扫描所有探针并检查它是否满足这两个约束。 如果是，则更新最低成本。 这是正确的，因为它显式评估每个探测的可行性，但每个查询需要 n 个检查，从而导致 O(nq) 操作。 当 n 和 q 都达到 10^5 时，这会导致多达 10^10 次比较，这远远超出了 2 秒可以处理的范围。 

关键的观察是每个探针都是 2D 空间中的静态点，并且每个查询都要求矩形优势区域中的点之间的最小成本。 这是对一组静态点的二维范围最小查询。 我们可以通过按一个坐标对探针进行排序并在扫描中处理查询来转换问题，同时保持第二个坐标上的结构。 

标准技巧是按温度降序对探针进行排序，并按温度降序处理查询。 当我们通过温度阈值时，我们“激活”对所有即将到来的查询有效的探测器。 一旦探测器激活，它就会贡献其风力能力和成本。 然后我们需要支持：在风≥w的所有有源探测器中，找到最小成本。 

这成为风值的动态前缀最小问题。 由于风值很大（高达 10^9），因此我们在探测器和查询中压缩它们。 然后，我们维护一个线段树或芬威克树，存储风指数的最小成本。 每个探针更新一个位置，每个查询都要求后缀最小查询。 

扫描确保了正确性，因为在我们处理温度为 t 的查询时，所有 x ≥ t 的探针都已激活，并且不包括不合格的探针。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(1) | O(1) | 太慢了 |
 | 扫描+线段树| O((n+q) log n) | O((n+q) log n) | O(n) | 已接受 |

 ## 算法演练

 1.收集所有探针和查询，并提取所有风值进行坐标压缩。 这是必要的，因为无法直接索引高达 10^9 的风范围。 
2. 按温度降序对探头进行排序。 这确保了当我们处理阈值 t 的查询时，已经考虑了每个具有足够温度的探针。 
3. 按温度降序对查询进行排序，同时保留原始索引。 这使我们能够以正确的依赖顺序回答查询。 
4. 在压缩的风坐标上初始化线段树，最初存储一个非常大的值。 该树代表每个风级的所有激活的探测器中的最小成本。 
5. 将指针保持在探针列表上。 对于按温度降序排列的每个查询，重复激活温度至少为查询阈值的所有探测器。 激活意味着将它们的成本插入线段树的风向位置，更新最小值。 
6. 为查询插入所有有效探针后，在线段树上执行后缀查询，以查找 Wind ≥ 所需的 Wind。 这将返回满足这两个约束的所有探测中的最小成本。 
7. 如果结果从无穷大不变，则输出-1。 否则输出计算出的最小值。 

线段树负责根据风约束进行过滤，而扫描则确保始终满足温度约束。 

### 为什么它有效

 在温度阈值 t 处理的任何查询中，活动集恰好包含满足温度要求的探针。 由于探针永远不会被删除，因此活动集只会在正确性方面增长，永远不会包含无效的探针，也永远不会排除以后需要的有效探针。 线段树强制在每个查询中只考虑具有足够风的探针，因此返回的最小值恰好超过了可行集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

class SegTree:
    def __init__(self, n):
        self.n = 1
        while self.n < n:
            self.n *= 2
        self.t = [INF] * (2 * self.n)

    def update(self, i, v):
        i += self.n
        if v >= self.t[i]:
            self.t[i] = min(self.t[i], v)
        else:
            self.t[i] = v
        i //= 2
        while i:
            self.t[i] = min(self.t[2*i], self.t[2*i+1])
            i //= 2

    def query(self, l):
        # minimum on [l, n)
        l += self.n
        r = self.n + self.n - 1
        res = INF
        while l <= r:
            if l % 2 == 1:
                res = min(res, self.t[l])
                l += 1
            if r % 2 == 0:
                res = min(res, self.t[r])
                r -= 1
            l //= 2
            r //= 2
        return res

def main():
    n, q = map(int, input().split())
    x = list(map(int, input().split()))
    y = list(map(int, input().split()))
    c = list(map(int, input().split()))

    probes = [(x[i], y[i], c[i]) for i in range(n)]

    qs = []
    ws = []

    for i in range(q):
        t, w = map(int, input().split())
        qs.append((t, w, i))
        ws.append(w)

    coords = sorted(set(ws))
    comp = {v:i for i,v in enumerate(coords)}

    probes.sort(reverse=True)
    qs.sort(reverse=True)

    st = SegTree(len(coords))

    ans = [-1] * q
    j = 0

    for t, w, idx in qs:
        while j < n and probes[j][0] >= t:
            _, yy, cc = probes[j]
            st.update(comp[yy], cc)
            j += 1

        pos = comp[w]
        res = st.query(pos)
        if res < INF:
            ans[idx] = res

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    main()
```该代码首先压缩风值，以便线段树保持紧凑。 探针按温度降序排序，以便激活是单调的。 每次激活都会在其风索引处插入探测成本，并且线段树维护每个风阈值的最小成本。 

查询函数从所需的风向上执行后缀最小值。 这符合条件“wind ≥ w”。 主循环仔细地将探针激活与查询处理对齐，以便不会遗漏或过早包含探针。 

一个微妙的点是多个探测器可以共享相同的风坐标； 线段树自然地通过仅存储每个位置的最小成本来解决这个问题，这已经足够了，因为我们只关心最便宜的有效探针。 

## 工作示例

 考虑示例输入：

 探头：

 (1,3,3), (2,1,1), (3,2,2)

 查询：

 (1,2), (1,3), (3,3)

 风压缩后[1,2,3]，我们在降低温度的情况下处理查询。 

| 查询 | 有源探头| 线段树状态（风：最小成本）| 回答 |
 | ---| ---| ---| ---|
 | (3,3) | (3,2,2) | (3,2,2) | 2 风=2 | -1 |
 | (1,3) | 所有探头 | 1 在风 = 1 时， 2 在风 = 2 时， 3 在风 = 3 时 | 3 |
 | (1,2) | 所有探头 | 相同| 1 |

 该跟踪显示了激活如何逐渐扩展可行集，而风过滤则通过后缀查询进行。 

第二个例子：

 探头：

 (10,1,5), (1,10,5)

 查询：(5,5)

 | 查询 | 有源探头| 线段树状态| 回答 |
 | ---| ---| ---| ---|
 | (5,5) | 无（仅第一个 10≥5，但风=1 <5；第二个温度无效）| 部分 | -1 |

 这证实仅满足一个维度是不够的。

 ## 边缘情况

 当多个探头共享相同的温度但不同的风值时，就会出现极端情况。 在这种情况下，激活顺序并不重要，因为所有的激活顺序都插入在具有较低或相同温度的任何查询之前，并且线段树独立处理风过滤。 

另一种边缘情况是所有探测对于查询都无效。 对于该后缀范围，线段树保持无穷大，并且算法无需特殊处理即可正确输出 -1。
