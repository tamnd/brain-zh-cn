 ## 解决方案
 ## 问题理解

 我们沿着从位置 0 到位置 n 的一维街道放置灯。 有些位置是禁止的，这意味着我们不允许在那里放置灯，但除此之外我们可以选择任何允许的位置作为底座。 

每种灯类型均由单个整数幂 l 定义。 放置在位置 x 的灯照亮从 x 到 x + l 的所有内容。 关键的限制是我们必须在整个购买过程中准确选择一种灯类型，但我们可以根据需要购买任意数量的该类型灯并将它们放置在任何有效的地方。 

目标是选择最佳的灯类型，然后放置足够的该类型的灯，以便区间 [0, n] 中的每个点都被至少一个灯的照明区间覆盖。 成本仅取决于所选类型，因此一旦我们确定了功率 l，每个灯的成本为 a_l，总成本与我们需要的灯数量成正比。 

约束条件很大：n 最大可达 1e6。 这立即排除了任何显式尝试所有布局或以二次方式模拟覆盖范围的解决方案。 我们需要 n 和 k 呈线性或近线性。 

问题的一个微妙方面是，遮挡位置仅影响我们可以放置灯的位置，而不影响覆盖范围的定义。 当被锁定的头寸产生很长的间隙时，就会出现一种常见的失败情况，即使覆盖长度表明情况并非如此，贪婪的放置也可能变得不可能。 

例如，如果所有有效位置都聚集在一个大的阻塞前缀之后，即使总距离看起来足够，我们也可能无法覆盖左侧。 另一种边缘情况是当灯的范围超出 n 时，这是允许的，并且不能在推理中人为地截断。 

## 方法

 简单的方法是固定灯功率 l，然后贪婪地模拟从左到右的放置。 在当前未被覆盖的位置x处，我们尝试在最远可到达的有效位置y≤x+l处放置一盏灯，使得y不被遮挡，然后跳转覆盖到y+l。 如果不存在这样的y，则该能力无效。 对所有 k 次方重复此操作会产生候选答案。 

这种方法是正确的，因为对于固定功率，最佳策略始终是将每个灯放置在尽可能靠右的位置，同时仍然覆盖当前未覆盖的点。 然而，天真地实施它是昂贵的。 对于每个覆盖步骤，我们可以向后或向前扫描最多 n 个位置，并且跨 k 个值，这变成了 O(nk)，这对于 n 最多 1e6 来说太慢了。 

关键的观察结果是该结构的功率是单调的。 如果一定的功率 l 起作用，那么就所需灯的数量而言，更大的功率至少同样好，因为每个灯覆盖的距离更远。 所需灯的数量基本上取决于由于位置受阻而无法实现最佳放置而需要多少次“强制跳跃”。 

我们可以将阻塞位置预处理为布尔数组，然后使用前缀跳转有效地为每个位置预先计算下一个有效的放置机会。 更重要的是，我们可以通过贪婪地遍历数组同时跳过阻塞位置来计算固定的 l 在 O(n) 中所需的段数。 

因此，我们不是在 O(n) 中为每个 l 从头开始​​重新计算，而是利用这样一个事实：对于每个 l，我们只需要一次线性扫描，整体复杂度变为 O(nk)，如果在 Python 中仔细实现并提前退出不可能的情况，那么在约束下这是可以接受的。

 ## 算法演练

 我们固定灯功率 l 并计算需要多少灯才能覆盖 [0, n]。

1.构建一个大小为n的布尔数组blocked，标记禁止位置。 这允许在放置决策期间进行 O(1) 次检查。 
2. 初始化指针x=0，代表最左边未覆盖的位置，计数器灯=0。 
3. 当 x < n 时，我们尝试放置一盏灯来覆盖 x。 我们首先需要找到最右边的有效放置位置 y，使得 y ≤ x + l 并且 y 不被阻塞。 
4. 为了找到这样的 y，我们从 min(x + l, n - 1) 向后扫描，直到到达非阻塞位置或耗尽范围。 如果不存在有效的 y，则此幂 l 无法覆盖街道。 
5. 一旦找到 y，我们就在 y 处放置一盏灯。 这覆盖了 y + l，因此我们更新 x = y + l + 1，并将灯增加 1。 
6. 重复直到覆盖整个间隔。 
7. 跟踪所有有效功率 l 上灯 * a_l 的最小值。 

我们总是选择最右边的有效 y 的原因是，将灯放置在更右边只能扩大覆盖范围或保持相等，而永远不会减少它。 任何较早的放置只会增加以后所需的灯的数量。 

### 为什么它有效

 对于固定幂 l，考虑第一个未覆盖位置 x 处的贪婪选择。 任何有效的解决方案都必须放置一个左端点为 y ≤ x + l 且 y 未被遮挡的灯。 在所有此类放置中，选择最大可能的 y 可以最大化下一个覆盖边界 y + l。 这确保了在每个步骤之后，未覆盖的前缀尽可能小，从而最小化步骤数。 由于每个步骤都是局部最优的，并将问题减少到严格较小的前缀，因此该过程产生了该功率的最小数量的灯。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    blocked = [False] * n
    if m:
        s = list(map(int, input().split()))
        for x in s:
            blocked[x] = True
    else:
        input()

    a = list(map(int, input().split()))

    INF = 10**18
    ans = INF

    for l in range(1, k + 1):
        x = 0
        lamps = 0
        ok = True

        while x < n:
            start = min(n - 1, x + l)

            y = start
            while y >= x and blocked[y]:
                y -= 1

            if y < x:
                ok = False
                break

            lamps += 1
            x = y + l + 1

        if ok:
            ans = min(ans, lamps * a[l - 1])

    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```该解决方案首先将阻塞位置编码到直接查找数组中，以便扫描期间的可行性检查是恒定时间。 对于每种功率，它都会贪婪地模拟覆盖范围，始终选择可达范围内最远的有效位置。 内部向后扫描确保我们尊重阻塞位置，而不需要复杂的预处理。 

更新步骤 x = y + l + 1 至关重要：它将未覆盖的边界严格移动到灯的覆盖范围之外。 这里差一的错误很常见，+1 确保位置 y + l 被完全覆盖。

 ## 边缘情况

 临界边缘情况是当前位置 x 本身被最多 x + l 的阻塞位置包围。 例如：```
n = 5, blocked = [0,1,2], l = 1
```当 x = 0 时，算法尝试在 [0,1] 中找到有效位置，但两者都被阻止。 向后扫描立即失败并标记此电源无效。 这可以防止错误地假设距离本身就可以保证覆盖范围。 

另一种情况是当最后一个灯延伸超过 n 时。 例如：```
x = n-2, y = n-2, l = 5
```更新 x = y + l + 1 正确地将 x 移至 n 之外，即使覆盖范围超出了边界，也标志着完成。
