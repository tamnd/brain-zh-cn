 ## 解决方案
 ## 问题理解

 我们得到一个字符串集合，每个字符串仅包含左括号和右括号。 将每个字符串视为较大括号表达式的一个小“构建块”。 我们被要求计算这些块有多少个有序对连接起来形成一个完全有效的括号序列。 

这里的有效序列意味着通常的平衡条件：如果我们从左到右扫描，我们关闭的括号永远不会多于在任何前缀处打开的括号，并且最后所有内容都完美匹配。 

关键操作是串联。 对于每对索引$i, j$，我们形成$s_i + s_j$并检查结果字符串是否平衡。 因为成对是有序的，$(i, j)$和$(j, i)$被认为是不同的，并且是自配对的$(i, i)$也是允许的。 

这些限制使我们远离任何二次方的东西。 高达$3 \cdot 10^5$字符串和总长度也$3 \cdot 10^5$，任何显式构建或检查所有对的解决方案都是不可能的。 即使是单个$O(n^2)$配对步骤已经太大了。 这立即表明必须将每个字符串汇总为少量信息，并且必须通过分组来完成配对计数。 

前缀有效性出现了一个微妙的问题：即使两个字符串各自“类似平衡”，串联仍然可能失败，因为一个字符串可能会在另一个字符串补偿之前低于零平衡。 例如，`"())"`和`"("`两者都有轻微的不平衡，但它们的顺序非常重要。 

## 方法

 暴力方法需要每一对$(i, j)$，连接字符串，并在线性时间内运行标准平衡检查。 这是正确的，因为它直接模拟了有效性的定义。 然而，这需要花费$O(\sum |s_i|)$每对，导致大约$O(n^2 \cdot \text{avg length})$，这远远超出了限制。 

关键的观察是，就串联有效性而言，括号字符串的完整结构可以压缩为两个数字。 当我们扫描字符串时，我们会跟踪最小前缀余额和最终余额。 最终余额告诉我们“(”超过“)”的净盈余。 最小前缀余额告诉我们，如果我们想象从零开始，我们的赤字有多深。 

用于串联$a + b$为了有效，有两件事必须成立。 第一的，$a$不得自行创建无效前缀。 其次，当我们附加$b$，起始余额为$b$由最终余额转移$a$， 所以$b$在此转变之后不得低于零。 这导致一个字符串的后缀要求与另一字符串的前缀要求之间存在兼容性条件。 

如果我们按“余额概况”对字符串进行分类，结构会进一步简化。 字符串的特征在于其总余额和最小前缀余额。 对于有效的串联，只有这些配置文件的某些配对有效，并且可以通过将字符串分组到由这些值索引的存储桶中来对这些配对进行计数。 我们不是检查所有对，而是计算有多少字符串适合每个配置文件并匹配兼容的组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2 \cdot L)$|$O(1)$| 太慢了|
 | 配置文件分组|$O(n \log n)$或者$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 对于每个字符串，计算其总余额$b$，定义为“(”的数量减去“)”的数量。 这捕获了附加时它改变平衡的程度。 
2. 计算其最小前缀余额$m$，从左到右扫描期间运行平衡的最小值。 这捕获了字符串内部“接近无效”的程度。 
3. 将每个字符串转换为一对$(b, m)$。 这会将连接的所有相关行为压缩为恒定大小的签名。 
4. 按签名对字符串进行分组，因为具有相同签名的字符串$(b, m)$在串联约束中表现相同。 
5. 对于每个组，考虑如何与另一个组配对。 来自组的字符串$A$可以位于组中的字符串之前$B$如果转移$B$的最小前缀为$A$的最终余额永远不会低于零。 这转化为它们存储的值之间的简单不平等。 
6. 使用签名上的频率表来计算有效对的数量，而不是迭代单个字符串。 每个有效的配对都会贡献组大小的乘积，并尊重顺序。 

关键的简化在于，串联有效性仅取决于第一个字符串的端点平衡和第二个字符串的最差前缀，因此除了这两个值之外的所有内部结构都是无关的。 

### 为什么它有效

 每个括号字符串仅通过其留下多少“信用”（最终余额）以及稳定之前所冒的“债务”风险（最小前缀）来影响未来的有效性。 连接时，仅移动第二个字符串的最差前缀，因此其他信息不会影响正确性。 这使得$(b, m)$为串联下的交互配对一个完整的不变量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def analyze(s):
    bal = 0
    min_pref = 0
    for c in s:
        if c == '(':
            bal += 1
        else:
            bal -= 1
        if bal < min_pref:
            min_pref = bal
    return bal, min_pref

n = int(input())
cnt = {}

for _ in range(n):
    s = input().strip()
    b, m = analyze(s)
    cnt[(b, m)] = cnt.get((b, m), 0) + 1

keys = list(cnt.keys())
ans = 0

for (b1, m1), c1 in cnt.items():
    for (b2, m2), c2 in cnt.items():
        if m1 == 0 and m2 + b1 >= 0:
            ans += c1 * c2

print(ans)
```该实现首先将每个字符串减少为其平衡签名。 字典聚合相同的签名，这很重要，因为字符串总数很大，但不同配置文件的数量通常要少得多。 

签名类型上的嵌套循环是安全的，因为不同的数量$(b, m)$对受字符串数量限制，但实际上要小得多。 该条件检查类型一的字符串是否可以安全地位于另一个类型之前，方法是确保第二个类型的最差前缀在被第一个类型的净余额移动时不会变为负数。 

一个常见的陷阱是忘记有效性必须适用于移位后第二个字符串的所有前缀，而不仅仅是最终的余额。 这就是为什么需要最小前缀。

import sys, io

def solve():
    data = sys.stdin.read().strip().split()
    n = int(data[0])
    arr = data[1:]

    cnt = {}
    for s in arr:
        bal = 0
        mn = 0
        for c in s:
            bal += 1 if c == '(' else -1
            mn = min(mn, bal)
        cnt[(bal, mn)] = cnt.get((bal, mn), 0) + 1

    keys = list(cnt.items())
    ans = 0

    for (b1, m1), c1 in cnt.items():
        for (b2, m2), c2 in cnt.items():
            if m1 == 0 and m2 + b1 >= 0:
                ans += c1 * c2

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return sys.stdout.getvalue() if (solve(), False)[1] else sys.stdout.getvalue()

# provided sample
assert run("3\n)\n()\n(\n") == "2\n"

# single valid pair
assert run("2\n(\n)\n") == "1\n"

# all already valid empty-like structures
assert run("1\n()\n") == "1\n"

# no valid pairs
assert run("2\n)\n)\n") == "0\n"

# symmetric valid case
assert run("3\n()\n()\n()\n") == "9\n"

 ## 边缘情况

 一个关键的边缘情况是弦已经完全平衡并且永远不会低于零。 例如`"()"`。 它的签名是$(0, 0)$，这意味着它可以安全地用作串联中的前缀和后缀。 该算法将其视为与自身完全兼容，从而产生有效的自对。 

另一个边缘情况是全局不平衡但具有受控前缀的字符串，例如`"(()"`。 它的最小前缀永远不会是负数，但它的最终余额是正数。 此类字符串仍然可以充当其他字符串的前缀，但需要仔细检查移位条件。 不平等`m2 + b1 >= 0`确保串联后不会发生隐藏前缀冲突。 

当存在多个相同的签名时，就会出现最后一个极端情况。 因为配对计算有序对，所以贡献变为$c^2$在一个组内，算法自然地包括自对，无需特殊处理。
