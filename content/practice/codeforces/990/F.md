 ## 解决方案

 ## 问题理解

 我们得到一个连通的无向图，其中结点为顶点，管道为边。 每条边必须分配一个整数流值，并且该值可以用方向来解释：正值表示流从第一个端点流向第二个端点，负值表示流向相反。 

每个结点都有一个所需的净余额值。 如果该值为正，则节点接收的单位数必须多于发出的单位数。 如果为负，则它发出的单位数必须多于接收的单位数。 换句话说，对于每个节点，所有关联边上的传入流量减去传出流量的总和必须等于给定值。 

任务是决定是否可以将整数流分配给边，以便同时满足所有节点平衡，如果可以，则构造一个有效的分配。 

约束很大，有多达 200,000 个节点和边，因此任何解决方案在图的大小上都必须基本上是线性的。 二次或偶数$O(n \log n)$常量较大的情况下有超时的风险。 该图保证是连接的，这消除了单独处理多个组件的需要，但这也意味着约束必须在整个结构上全局平衡。 

一个关键的隐含约束是流量守恒。 如果我们将所有节点余额相加，则每条边贡献一次作为传入，一次作为传出，因此所有节点的总和$s_i$必须为零。 如果不是，那么答案是不可能的。 

当一种简单的方法试图在不考虑全局平衡传播的情况下贪婪地分配流量时，就会出现微妙的边缘情况。 例如，在树状结构中，从叶子向上推多余的部分是可行的，但在具有循环的图中，天真的贪婪取消可能会产生矛盾，除非通过生成树和循环处理仔细构建。 

当节点具有非零需求但仅通过已由早期贪婪步骤“完全确定”的边连接时，会出现另一种失败情况。 当独立处理边缘而不是强制执行全局守恒定律时，通常会发生这种情况。 

## 方法

 一种强力的观点是将每个边缘流视为未知变量，并为每个节点编写一个线性方程。 这产生了一个系统$n$线性方程组$m$变量。 从概念上讲，直接通过整数的高斯消去法来解决它是可行的，但它的复杂性是$O(n^3)$在最坏的情况下，在给定的限制下变得完全不可行。 即使稀疏优化也没有多大帮助，因为系统结构并不是纯粹的树状结构。 

关键的观察结果是，约束恰好是无向连通图上的流守恒系统。 这意味着有效解的空间不是任意的：任何满足节点约束的流分配都可以通过固定生成树然后使用不在树中的边来调整局部循环来构造。 

更具建设性的观点是扎根生成树并将问题视为通过树推动“过剩需求”。 每个节点最初都存在不平衡$s_i$。 如果我们在 DFS 树上自下而上处理节点，则每个子树都可以计算其总不平衡性，并且该不平衡性必须通过父边推动。 这减少了在树边缘分配流的问题，从而精确地取消子树和。 

然而，由于原始图可能包含循环，我们仍然必须为非树边赋值。 重要的见解是，这些边可以进行任意循环，并且仅用于确保基于树的构造在原始边集中保持有效。 一旦树边被固定以满足所有节点平衡，每个剩余的边都可以设置为零，而不影响正确性。 

这是可行的，因为仅生成树就足以路由连接图中的所有网络不平衡。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 强力线性系统| O(n^3) | O(n^3) | O(n^2) | O(n^2) | 太慢了|
 | DFS生成树+平衡传播| O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 我们构建一棵生成树并用它来传播平衡值。 

1. 通过验证所有的总和来检查全局的可行性$s_i$为零。 如果不是，则任何流分配都无法满足守恒，因为每条边都会在端点之间内部抵消。 
2. 构建图的邻接表并选择任意根，例如节点 1。 
3. 运行DFS构造父数组并记录生成树。 遍历时，避免再次访问父级以防止循环。 这确保我们准确地获得$n-1$连接所有节点的树边。 
4. DFS完成后，按后序计算子树不平衡性。 对于每个节点，定义一个等于其自身的值$s_i$加上所有来自儿童的捐款。 
5.带孩子回来时$v$给它的父级$u$，指定树边$(u, v)$流等于子树不平衡$v$，直接来自$v$到$u$。 做出这个选择是因为该流恰好抵消了以$v$，确保其内部平衡。 
6. 通过添加孩子的贡献来更新父母累积的不平衡，因为这种不平衡现在已经向上转移。 
7. DFS完成后，所有树边都分配了流，保证每个子树直到根为止都是平衡的，并且根是平衡的，因为总和为零。 
8. 对于所有非树边，将流分配为零，因为不需要它们来维护节点平衡。 

### 为什么它有效

 该算法保持了这样的不变性：在处理一棵子树之后，唯一剩余的不平衡通过恰好一个边缘向上推。 每个子树都将其总需求贡献给其父树，并且不会出现任何内部不平衡的情况。 因为图是连通的，所以每个节点的不平衡最终都会路由到根，并且根接收到的总和为零，从而确保了一致性。 由于每条边要么恰好携带一个子树流，要么携带零，因此所有节点方程都恰好满足一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n = int(input())
s = list(map(int, input().split()))
m = int(input())

g = [[] for _ in range(n)]
edges = []

for i in range(m):
    x, y = map(int, input().split())
    x -= 1
    y -= 1
    g[x].append((y, i))
    g[y].append((x, i))
    edges.append((x, y))

if sum(s) != 0:
    print("Impossible")
    sys.exit()

parent = [-1] * n
parent_edge = [-1] * n
vis = [False] * n
ans = [0] * m

def dfs(u):
    vis[u] = True
    for v, eid in g[u]:
        if not vis[v]:
            parent[v] = u
            parent_edge[v] = eid
            dfs(v)

dfs(0)

def solve(u):
    for v, eid in g[u]:
        if parent[v] == u:
            solve(v)
            s[u] += s[v]
            ans[eid] = s[v]

solve(0)

print("Possible")
print("\n".join(map(str, ans)))
```该解决方案首先通过检查需求总和来验证全局可行性。 然后，它使用 DFS 构建生成树，存储将每个节点与其父节点连接的边。 第二个 DFS 计算子树平衡，并为每个树边分配一个等于其子节点子树总和的流，向上朝向父节点。 

一个微妙的实现细节是我们必须区分树边和非树边。 在此实现中，只有通过 DFS 父关系发现的边才会被分配有意义的流值； 其他的则隐式保持为零。 递归限制会增加，因为图可能很深，可能会退化为链。 

## 工作示例

 考虑样本输入。 

输入：```
4
3 -10 6 1
5
1 2
3 2
2 4
3 4
3 1
```我们从节点 1 开始构造一棵 DFS 树。假设遍历沿边 (1-2)、(2-4)、(2-3) 构建父链接。 子树和向上传播。 

| 节点| 首字母 | 儿童总和 | 最终子树总和 |
 | --- | --- | --- | --- |
 | 3 | 6 | 0 | 6 |
 | 4 | 1 | 0 | 1 |
 | 2 | -10 | 6+1| -3 |
 | 1 | 3 | -3 | 0 |

 边所分配的流量等于子子树的总和：

 - (2,3) = 6
 - (2,4) = 1
 - (1,2) = -3

 这表明每个子树的不平衡都准确地向上传输并在根处消除。 

现在考虑一个简单的线图：

 输入：```
3
1 -2 1
2
1 2
2 3
```DFS 树就是图本身。 子树总和：

 - 节点 3 = 1
 - 节点 2 = -1
 - 节点 1 = 0

 边缘分配：

 - (2,3) = 1
 - (1,2) = -1

 每个节点的平衡条件都得到准确满足，从而确认了最小链情况下的正确性。

 ## 边缘情况

 一个关键的边缘情况是，所有需求总和为零，但以强制长传播链的方式分布。 在第一个节点需要吸收较大正值而最后一个节点具有相同负值的折线图中，算法正确地逐步推动不平衡，直到到达根。 每个中间节点只是简单地转发累积值而不进行修改，这防止了局部矛盾。 

另一个边缘情况是星形图，其中许多叶具有非零需求。 每片叶子的不平衡都会直接发送到中心，中心将它们聚合起来。 该中心成为平衡枢纽，由于总和为零，它正好取消了自己的需求。 

最后，具有许多循环的稠密图仍然表现正确，因为仅使用生成树进行传播。 额外的边缘不会产生干扰，因为它们不需要承载非零流量，从而避免了循环循环中的模糊性。
