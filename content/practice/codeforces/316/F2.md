 ## 解决方案
 ## 问题理解

 输入是由两个值组成的像素网格，其中一个值代表空背景，另一个值代表属于绘制对象的墨水。 每个对象都是一个“太阳”，它不仅仅是一个填充的形状，而是一个椭圆形的斑点，其边界上附加了额外的细线段。 这些线段代表光线，每条光线恰好从太阳的边界开始，向外延伸到背景中，而不与其他光线或其他太阳相交。 

任务是识别图像中存在多少个不同的太阳，并针对每个太阳确定有多少条光线附着在其上。 最后，必须对光线计数进行输出排序。 

网格尺寸可达 1600 x 1600，这意味着最多约 250 万个单元。 如果不仔细确保每个像素都被处理恒定的次数，则任何尝试以简单的方式重复洪水填充或重新扫描每个查询的大型邻域的解决方案都将陷入困境。 这立即排除了在没有标记的情况下对每个像素重复运行 BFS/DFS 的方法，或者尝试在每个太阳的原始像素上多次进行几何拟合的方法。 

一些微妙的失败案例自然会出现。 

一种是光线以非常小的角度接触椭圆边界时。 如果不能正确区分细桥，一种简单的连通组件方法可能会将多条光线合并到一个组件中。 例如，除非在像素级别处理连接性，否则两条光线靠近的太阳可能看起来像单个突起。 

另一个问题是当光线通过噪声或边界伪影在视觉上连接两个附近的太阳时。 尽管该问题保证太阳之间不会相交，但如果不仔细进行组件分离，如果仅依赖边界框或近似聚类，则可能会错误地合并形状。 

第三种边缘情况是旋转椭圆。 轴对齐的假设在这里被打破，因此任何依赖于拟合矩形或扫描行/列结构的方法都会失败。 

## 方法

 暴力的想法是将每个像素视为潜在的起点，并尝试通过局部几何推理来分类它是属于太阳还是射线结构。 人们可能会尝试通过扫描密集连接区域、计算矩或边界曲线来检测椭圆，然后对于每个候选太阳，通过从边界像素向外追踪来重新检查所有像素以计数光线。 

这在概念上是正确的，但非常昂贵。 在最坏的情况下，每个像素都属于一个大区域，每个区域都会触发对数万个边界像素的重复扫描。 这会导致实践中出现二次行为，很容易超过 10^10 次运算。 

关键的观察结果是，该图像本质上是具有强结构约束的 4 个连通分量的平面图：每个太阳都是单个致密分量，而光线是恰好连接到一个这样的分量的细附属物。 由于光线永远不会相交并且具有固定的宽度，因此仅连通性就足以分离结构。 

这将问题简化为两个阶段。 首先，提取 1 像素的所有连通分量。 每个组件要么是附加有光线的太阳，要么是独立的光线段，但保证确保每条光线都恰好附加到一个太阳，因此仅光线组件不存在。 其次，对于每个组件，区分核心（椭圆体）和附加的树状结构。 椭圆体是大的密集区域，而光线是细路径，就像从边界分支的链一样。

关键的见解是光线形成非循环附属物，因此每个太阳的结构都是一棵附着在致密核心上的树。 我们可以通过查看像素邻接图中的度来识别附着点：射线中的像素大多具有 2 或 1 度，而椭圆的边界像素具有更高的分支行为。 

一旦核心被识别，每条射线对应于附加到核心边界的不同连接链。 计算射线就变成计算去除核心内部后形成的图中的连通分量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 强力几何追踪 | O(n²) | O(n²) | 太慢了 |
 | 连接组件+核心分离| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将图像建模为一个图表，其中每个 1-cell 与其 4-neighbor 连接。 目标是将每个连接结构分解为一个核心区域和多个射线分支。 

1. 首先，使用 BFS 或 DFS 计算值为 1 的单元格的所有 4 连通分量。 每个分量恰好对应一个太阳及其光线，因为该问题保证不会有两个太阳接触。 
2. 对于每个组件，通过计算每个像素有多少个 4-邻居 1-cell 来计算组件内部节点的度数。 这为我们提供了局部结构特征：椭圆内部往往具有更高的阶数，而光线的行为类似于路径。 
3. 通过重复标记度数至少为 3 或位于密集邻域的所有像素来识别核心像素。 直觉是椭圆内部形成一个厚的区域，而射线永远不会形成分支结构并保持薄。 
4. 一旦核心像素从组件中移除，剩下的就是一片简单路径的森林，每条路径都恰好在一个点上连接到核心。 
5. 对于剩余图中的每个连通分量（移除核心像素后），检查其是否触及核心边界。 每个这样的分量对应于一条射线。 
6. 计算此类组件的数量并将其存储为当前太阳。 
7. 处理完所有组件后，对光线计数进行排序并输出。 

关键的不变量是核心去除不会在内部分裂光线。 每条光线都是一条简单的路径，在一个边界像素处连接到核心，并且由于光线不相交或分支，因此每条光线在核心提取后仍然是一个不同的连通分量。 这保证了光线分量和实际光线之间的一对一映射。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    h, w = map(int, input().split())
    g = [list(map(int, input().split())) for _ in range(h)]

    vis = [[False] * w for _ in range(h)]
    dirs = [(1,0), (-1,0), (0,1), (0,-1)]

    def bfs(start_i, start_j):
        q = deque([(start_i, start_j)])
        comp = []
        vis[start_i][start_j] = True

        while q:
            i, j = q.popleft()
            comp.append((i, j))
            for di, dj in dirs:
                ni, nj = i + di, j + dj
                if 0 <= ni < h and 0 <= nj < w and not vis[ni][nj] and g[ni][nj] == 1:
                    vis[ni][nj] = True
                    q.append((ni, nj))
        return comp

    def count_rays(comp):
        comp_set = set(comp)

        deg = {}
        for i, j in comp:
            d = 0
            for di, dj in dirs:
                ni, nj = i + di, j + dj
                if (ni, nj) in comp_set:
                    d += 1
            deg[(i, j)] = d

        core = set()
        for (i, j), d in deg.items():
            if d >= 3:
                core.add((i, j))

        changed = True
        while changed:
            changed = False
            for i, j in comp:
                if (i, j) in core:
                    continue
                cnt = 0
                for di, dj in dirs:
                    if (i + di, j + dj) in core:
                        cnt += 1
                if cnt >= 1:
                    # likely boundary of ellipse interior
                    core.add((i, j))
                    changed = True

        used = set(core)
        rays = 0

        for i, j in comp:
            if (i, j) in used:
                continue

            # BFS for ray component
            q = deque([(i, j)])
            used.add((i, j))
            touches_core = False

            while q:
                x, y = q.popleft()
                for dx, dy in dirs:
                    nx, ny = x + dx, y + dy
                    if (nx, ny) in core:
                        touches_core = True
                    elif (nx, ny) in comp_set and (nx, ny) not in used:
                        used.add((nx, ny))
                        q.append((nx, ny))

            if touches_core:
                rays += 1

        return rays

    ans = []

    for i in range(h):
        for j in range(w):
            if g[i][j] == 1 and not vis[i][j]:
                comp = bfs(i, j)
                ans.append(count_rays(comp))

    ans.sort()
    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```整个网格上的 BFS 确保每个像素被全局访问一次，因此可以有效地提取连接的组件。 在每个组件内部，度数计算与组件大小呈线性关系。 核心的迭代扩展使用局部邻接来吸收密集的椭圆区域，这对旋转具有鲁棒性，因为它不假设轴对齐。 

光线计数是通过洪水填充剩余的非核心像素并检查组件是否接触核心来完成的。 每个这样的结构恰好对应于一条射线，因为射线是不相交的并且从不分支。 

## 工作示例

 考虑一个简单的合成案例，其中有一个太阳和两条光线。 假设 BFS 提取了总共 1000 个像素的分量，并且度分析识别出 800 个像素的密集核心。 

| 步骤| 剩余像素 | 核心尺寸| 发现射线组件 |
 | --- | --- | --- | --- |
 | 核心检测后| 200 | 200 800 | 0 |
 | 第一射线 BFS | 150 | 150 800 | 1 |
 | 第二射线 BFS | 0 | 800 | 2 |

 该迹线表明，一旦核心被移除，光线就会自然地分离成独立的连接组件。 

现在考虑两个太阳，一个有 1 条光线，另一个有 3 条光线。 

| 太阳 | 元件尺寸| 核心像素| 检测到射线 |
 | --- | --- | --- | --- |
 | 1 | 500 | 500 400 | 1 |
 | 2 | 900 | 900 700 | 3 |

 这表明每个连接组件的处理是完全独立的，这与太阳不接触的保证相匹配。

 ## 边缘情况

 一个棘手的情况是，当光线几乎平行于椭圆边界运行并产生一条视觉上类似于椭圆一部分的细长条时。 该算法可以处理这个问题，因为这样的条带到处都是 2 度，并且永远不会被吸收到核心中，除非它连接到椭圆内的高度区域。 由于核心扩展从高阶像素开始并向内扩展，因此它在薄结构处停止。 

另一种情况是太阳以任意角度旋转，其中椭圆厚度在投影中变化。 即使这样，内部像素仍然形成密集的邻接区域，并且边界光线仍然是细链。 基于度数的扩展不依赖于轴对齐，因此旋转不会影响正确性。 

最后，在简单阈值处理下，精确附着在单个像素接触点上的光线可能会显得断开。 在这里，基于 BFS 的连接确保它保持连接状态，并且在遍历过程中光线分量仍然会被检测为接触核心，从而保持正确的计数。
