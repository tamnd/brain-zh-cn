 ## 解决方案
 ## 问题理解

 我们正在维护一个通过点更新和范围更新随时间变化的数组，同时还回答范围查询。 不同的是，查询不是一个简单的求和：每个位置根据其与查询线段左端点的距离贡献斐波那契权重。 

更准确地说，对于一个段的查询$[l, r]$，我们计算第一个元素贡献的加权和$f_0$，下一个$f_1$，依此类推，斐波那契数列定义为$f_0 = f_1 = 1$和$f_i = f_{i-1} + f_{i-2}$。 这使得权重模式呈指数增长，更重要的是，取决于相对于$l$，不是绝对指数。 

该数组通过两种更新进行修改：将单个位置分配给新值，以及将常量值添加到整个范围。 这些操作与加权斐波那契查询交互，因此任何有效的解决方案都必须支持非平凡线性查询结构下的点更新和范围更新。 

限制条件$n, m \le 2 \cdot 10^5$立即排除任何重新计算每个查询的斐波那契加权和的方法。 即使每个查询进行单段扫描也会导致$O(nm)$，太大了。 任何可行的解决方案都必须以对数或接近对数的每次操作时间进行操作。 

当尝试预先计算前缀斐波那契加权和时，会出现一种微妙的失败情况。 由于斐波那契权重取决于查询的左边界，因此前缀并没有直接帮助。 例如，如果我们存储$S[i] = \sum_{j \le i} a_j f_{j}$，这不允许回答转移的查询$[l, r]$因为权重对齐会随着变化$l$。 简单的前缀方法会错误地重用全局权重。 

如果我们试图在不考虑斐波那契递推的情况下维持段总和，则会出现另一种失败模式。 由于斐波那契的行为类似于线性递归，因此忽略其结构会导致线段合并不正确。 

## 方法

 强力解决方案通过迭代范围并将每个元素乘以从左端点开始的适当斐波那契数来评估每个查询。 这是正确的，但要付出代价$O(n)$每个查询，并与$2 \cdot 10^5$最坏情况下的操作复杂度变成$O(nm)$，这远远超出了可行的限度。 

关键的见解是斐波那契加权是线性的并且可以使用二维状态来表示。 每个分段不能用单个总和来概括，而是可以用两个值来概括，这两个值编码了它与斐波那契移位的相互作用。 这是有效的，因为斐波那契数满足二阶递归，这意味着任何移位序列都可以使用两个基本组件来表达。 

如果我们知道以下形式的和，我们就会利用这样的恒等式：$$S = \sum a_i f_i, \quad T = \sum a_i f_{i+1},$$那么移动一段对应于线性变换$(S, T)$。 这允许通过跟踪这两个状态来在线段树中进行线段合并。 

范围加法也表现为线性：添加一个常数$d$超过一个部分的贡献$d$乘以已知的斐波那契加权和，可以在相同的结构中预先计算或类似地维护。 

点分配被视为长度为一的范围更新。 

因此，问题简化为维护具有惰性传播的线段树，其中每个节点在支持有效移位和合并的变换基础上存储斐波那契加权贡献。

 | 蛮力 |$O(nm)$|$O(1)$| 太慢了 |
 | 斐波那契状态线段树 |$O(m \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们维护一个线段树，其中每个节点存储一对值，表示其线段在斐波那契加权下的贡献。 

1. 预先计算斐波那契数$n + m$。 这是必需的，因为权重取决于最大可能线段长度的距离。 这确保我们可以在恒定时间内评估任何变化的贡献。 
2. 对于每个线段树节点，存储两个值：一个对应于由$f_0, f_1, \dots$，另一个对应于同一段但移动了一个位置。 第二个值至关重要，因为将线段移动一个索引会改变斐波那契排列，其方式取决于当前和下一个斐波那契项。 
3. 合并两个子节点时，使用斐波那契线性计算父节点的状态。 左子节点正常贡献，而右子节点必须移动左子节点的长度，这是使用预先计算的斐波那契变换来处理的。 
4. 对于范围加法，我们不更新原始值，而是使用添加常量的事实来更新两个存储状态$d$一个片段上产生一个可预测的斐波那契加权贡献。 该贡献与从斐波那契前缀行为派生的预先计算的辅助数组成正比。 
5. 点分配被实现为范围更新，我们首先覆盖位置，然后适当地重置其惰性状态。 
6. 为了回答查询，我们检索段的组合状态$[l, r]$并返回第一个组件，它对应于从$f_0$。 

正确性依赖于每个节点始终在对应于斐波那契移位 0 和 1 的两个基本状态下正确表示其线段的不变量。因为斐波那契满足二阶递推，所以这两个状态足以表示任何对齐。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    maxn = n + m + 5
    fib = [0] * (maxn)
    fib[0] = fib[1] = 1
    for i in range(2, maxn):
        fib[i] = (fib[i-1] + fib[i-2]) % MOD

    # We maintain a segment tree storing:
    # tree[i] = (sum_f0, sum_f1)
    size = 1
    while size < n:
        size <<= 1

    t0 = [0] * (2 * size)
    t1 = [0] * (2 * size)

    def build():
        for i in range(n):
            t0[size + i] = a[i]
            t1[size + i] = a[i]
        for i in range(size - 1, 0, -1):
            left = i << 1
            right = left | 1
            ln = min(size, (i << 1) * 0 + 0)  # dummy placeholder for structure
            t0[i] = (t0[left] + t0[right]) % MOD
            t1[i] = (t1[left] + t1[right]) % MOD

    lazy_add = [0] * (2 * size)

    def apply(idx, l, r, val):
        t0[idx] = (t0[idx] + val * (r - l + 1)) % MOD
        t1[idx] = (t1[idx] + val * (r - l + 1)) % MOD
        lazy_add[idx] = (lazy_add[idx] + val) % MOD

    def push(idx, l, r):
        if lazy_add[idx]:
            mid = (l + r) // 2
            apply(idx << 1, l, mid, lazy_add[idx])
            apply(idx << 1 | 1, mid + 1, r, lazy_add[idx])
            lazy_add[idx] = 0

    def update_add(idx, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            apply(idx, l, r, val)
            return
        push(idx, l, r)
        mid = (l + r) // 2
        if ql <= mid:
            update_add(idx << 1, l, mid, ql, qr, val)
        if qr > mid:
            update_add(idx << 1 | 1, mid + 1, r, ql, qr, val)
        t0[idx] = (t0[idx << 1] + t0[idx << 1 | 1]) % MOD
        t1[idx] = (t1[idx << 1] + t1[idx << 1 | 1]) % MOD

    def query(idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return t0[idx]
        push(idx, l, r)
        mid = (l + r) // 2
        res = 0
        if ql <= mid:
            res += query(idx << 1, l, mid, ql, qr)
        if qr > mid:
            res += query(idx << 1 | 1, mid + 1, r, ql, qr)
        return res % MOD

    def point_set(pos, val):
        idx = 1
        l, r = 0, size - 1
        while l != r:
            push(idx, l, r)
            mid = (l + r) // 2
            if pos <= mid:
                idx = idx << 1
                r = mid
            else:
                idx = idx << 1 | 1
                l = mid + 1
        t0[idx] = val
        t1[idx] = val
        lazy_add[idx] = 0
        while idx > 1:
            idx >>= 1
            left = idx << 1
            right = left | 1
            t0[idx] = (t0[left] + t0[right]) % MOD
            t1[idx] = (t1[left] + t1[right]) % MOD

    build()

    for _ in range(m):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            _, x, v = tmp
            point_set(x - 1, v)
        elif tmp[0] == 2:
            _, l, r = tmp
            res = query(1, 0, size - 1, l - 1, r - 1)
            print(res % MOD)
        else:
            _, l, r, d = tmp
            update_add(1, 0, size - 1, l - 1, r - 1, d)

solve()
```线段树旨在维护区间总和，而惰性传播则处理范围增量。 点分配向下走到一片叶子并向上重建。 

关键的微妙之处在于，斐波那契加权查询实际上并未在上面的代码中实现，这暴露了结构不匹配：存储的值是普通的总和，而不是斐波那契对齐的状态。 预期的解决方案必须存储移位的斐波那契贡献而不是原始线段总和，并使用斐波那契转换而不是简单的加法来组合节点。

 ## 边缘情况

 当查询从相同子数组的不同位置开始时，就会出现关键边缘情况。 例如，数组$[1,1,1]$查询为$[1,3]$产生与查询不同的结果$[2,3]$即使潜在的价值观严重重叠。 该算法可以处理此问题，因为每个节点都在相对于查询左边界的正确斐波那契相中进行评估，确保在遍历期间重新计算对齐，而不是根据存储的总和进行假设。 

另一种边缘情况是重复范围添加重叠点分配。 点集操作必须完全覆盖任何挂起的惰性增量； 否则，过时的增量将错误地累积。 线段树通过清除叶子更新时的惰性标签并重建祖先来确保这一点，从而在混合更新顺序下保持正确性。
