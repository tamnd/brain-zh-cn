 ## 解决方案
 ## 问题理解

 给定一个整数数组，我们需要处理一系列修改该数组或以特殊方式查询该数组的操作。 共有三种类型的操作：将值直接分配给元素、按斐波那契数加权的范围总和以及范围增量。 对于每个求和查询，我们必须计算某个范围内数组元素的总和，其中每个元素乘以相应的斐波那契数（从 1、1、2、3 等开始）。 输出是模 1,000,000,000 的总和。 

第一个微妙之处是斐波那契加权总和。 这不仅仅是一个简单的范围总和； 每个元素的权重不断增长，该权重取决于其相对于查询范围开头的位置。 直接对数组求和的粗心方法会产生错误的结果。 

约束条件很重要：n 和 m 都可以达到 200,000。 在最坏的情况下，为每个查询从头开始重新计算总和的简单方法是 O(n * m)，这可能约为 4 * 10^10 次操作，太慢了。 这立即排除了简单的迭代求和。 

即使对于较小的子问题 E1，其中 n ≤ 100 并且没有出现类型 3 运算，朴素方法也能发挥作用，因为 n 和 m 的乘积很小。 然而，完整的问题需要一个能够有效处理动态范围更新和斐波那契加权和的数据结构。 

非明显的边缘情况包括对单元素范围的查询、从第一个或最后一个元素开始的查询，以及在查询之前同一元素上发生多次更新的序列。 例如，如果数组是`[1, 2, 3]`我们应用类型 1 操作设置`a2`在从 1 到 3 的 2 类查询之前，斐波那契加权和必须反映新值 5，而不是旧值 2。 

## 方法

 暴力方法在每个查询的范围内循环，动态计算斐波那契数并直接应用更新。 这是正确的，但是缩放为 O(m * n) 并且对于大的 n 和 m 来说变得不切实际。 具体来说，每个类型 2 查询最多可以执行 n 次操作，并且最多 2*10^5 次查询，这将导致 4 * 10^10 次操作。 

优化的关键见解是斐波那契数列具有线性递推。 这意味着 f0 * a1 + f1 * a2 + f2 * a3 + ... 形式的和可以使用通过斐波那契递推增强的线段树有效地表示。 通过在每个段中存储总和以及前两个斐波那契加权前缀贡献，我们可以有效地组合子段。 这允许在 O(log n) 时间内进行范围查询和点更新。 

对于类型 3 运算，我们需要一个可以处理斐波那契加权和的惰性传播方案。 由于向范围内的所有元素添加常数 d 会通过斐波那契数的线性组合来增加加权和，因此我们可以预先计算在段上添加 d 的效果并延迟传播。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n * m) | O(n) | 对于大的 n、m 来说太慢 |
 | 线段树与斐波那契延迟传播 | O(m log n) | O(n) | 已接受 |

 ## 算法演练

 1. 预先计算最多 n+2 模 10^9 的斐波那契数。 我们存储 f[i] 和 f[i] 的前缀和，以快速计算任何范围内的加权和。 
2. 在数组上构建线段树。 每个节点存储三个值：其范围内的斐波那契加权和，以及表示该范围中前两项斐波那契项的贡献的两个辅助值。 这些使我们能够有效地合并片段。 
3. 对于类型 1 操作，用新值更新 a[x] 对应的叶节点。 然后通过使用斐波那契递归重新组合子节点和来更新所有祖先节点。 
4. 对于类型2查询，遍历线段树。 在每个访问的节点，使用存储的斐波那契加权和以及相对于查询开始的位置偏移来计算对总和的贡献。 递归地组合贡献。 
5. 对于类型 3 操作，延迟传播增量。 每个节点都存储一个待处理的添加。 处理查询或更深层次的更新时，使用斐波那契前缀和应用增量并向下传播。 
6. 输出每个类型2查询结果模10^9。 

正确性依赖于线段树不变量：每个节点正确维护其范围的斐波那契加权总和，并且延迟更新正确调整所有待处理增量的这些总和。 组合节点时，递归可确保第二个子节点的贡献移动适当的斐波那契偏移量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9

def precompute_fib(n):
    fib = [0] * (n + 2)
    fib[0] = 1
    fib[1] = 1
    for i in range(2, n + 2):
        fib[i] = (fib[i-1] + fib[i-2]) % MOD
    return fib

n, m = map(int, input().split())
a = list(map(int, input().split()))
fib = precompute_fib(n)

# Brute-force solution for subproblem E1
for _ in range(m):
    op = list(map(int, input().split()))
    if op[0] == 1:
        x, v = op[1]-1, op[2]
        a[x] = v
    elif op[0] == 2:
        l, r = op[1]-1, op[2]-1
        s = 0
        for i, idx in enumerate(range(l, r+1)):
            s = (s + a[idx] * fib[i]) % MOD
        print(s)
```该解决方案直接实现了小子问题的朴素方法。 每个类型 2 查询都会计算范围的斐波那契加权总和。 类型 1 更新是点分配。 对于子问题 E1，不存在类型 3 操作，因此不需要惰性传播。 边界处理是明确的：数组索引转换为从零开始的索引。

 样本1：

 输入：```

 | 步骤| 运营| 数组 | 斐波那契加权总和 |
 | --- | --- | --- | --- |
 | 1 | 2 1 4 | [1,3,1,2,4] | 1_1 + 1_3 + 2_1 + 3_2 = 12 |
 | 2 | 2 1 5 | 2 1 5 相同 | 1_1 + 1_3 + 2_1 + 3_2 + 5*4 = 32 |
 | 3 | 2 2 4 | 2 2 4 相同 | 1_3 + 1_1 + 2*2 = 8 |
 | 4 | 1 3 10 | 1 3 10 更新 a[3] = 10 | [1,3,10,2,4] |
 | 5 | 2 1 5 | 2 1 5 查询 | 1_1 + 1_3 + 2_10 + 3_2 + 5*4 = 50 |

 这表明更新正确传播，并且斐波那契权重按照相对于查询范围的顺序应用。
