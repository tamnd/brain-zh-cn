 ## 解决方案
 ## 问题理解

 我们给定一个主字符串$s$和几个约束，每个约束由一个模式字符串组成$p$和一个数字区间$[l, r]$。 对于任意候选字符串$t$，我们可以数一下有多少次$t$显示为内部的子字符串$p$，其中出现次数按位置进行计数$p$，包括重叠。 字符串$t$如果该规则出现的次数在$p$位于区间内$[l, r]$。 如果一个字符串同时满足所有规则，则该字符串被称为好字符串。 

任务是考虑每个不同的子串$s$并数一下其中有多少是好的。 

关键结构是我们正在过滤子串$s$使用由_发生计数在其他字符串内部定义的约束，而不是在内部$s$本身。 这使得这个问题从根本上来说是关于比较子串$s$针对许多模式数据库并有效评估频率约束。 

约束的数量很少，最多 10 个模式，但字符串可能很大，最多 50000 个。这立即表明每个候选子字符串的处理必须非常高效。 枚举子串$s$已经是$O(|s|^2)$，因此任何解决方案都必须避免每个子字符串重复重新计算模式匹配。 

一种天真的方法会考虑每个子串$t$的$s$，并且对于每条规则，扫描模式$p$并计算出现次数$t$。 那至少是$O(|s|^2 \cdot |p|)$，这对于 50000 长度的字符串是完全不可行的。 

更微妙的失败模式来自子字符串匹配的部分重用。 即使我们建造一个自动机$s$，里面的难度不匹配$s$，但计算匹配项$t$在多个外部字符串内$p$， 在哪里$t$在后缀树状状态之间动态变化。 

一个具体的边缘情况说明了为什么朴素子串枚举会中断：

 输入：```
aaaaa
1
aaaaa 1 1
```的每个子串$s$也是一串重复的“a”。 一种幼稚的方法可能会反复重新计算出现的情况$p$，即使所有子串结构相似，也会导致冗余工作和时间爆炸。 

真正的挑战是聚合子串$s$在一个结构中，我们可以查询每个子字符串一次并跨规则重用信息。 

## 方法

 暴力解决方案迭代所有子字符串$t = s[i..j]$，并且对于每条规则$(p, l, r)$，它计算出现次数$t$在$p$。 计算出现次数本身是$O(|p|)$使用朴素匹配或 KMP，因此整体复杂性变为$O(|s|^2 \cdot \sum |p|)$，这远远超出了任何限制。 

甚至优化出现计数$O(|p|)$每个子串仍然没有帮助，因为子串的数量是二次的。 

关键的观察是我们不应该独立地处理子串。 相反，我们构建了一个后缀自动机$s$，它紧凑地表示所有不同的子字符串。 每个状态对应于一组共享相同结束位置和结构的子串，并且转换对应于按字符扩展子串。 

一旦我们有了这个结构，每个子串$s$每个状态间隔只表示一次，我们可以计算每个状态而不是每个子串的贡献。 

现在问题归结为计算，对于每个状态（代表一组子串），该状态中有多少子串满足所有规则。 每个规则都需要计算，对于固定的模式$p$, 每个子串出现多少次$t$出现在$p$。 这相当于匹配所有子串$p$反对后缀自动机$s$, then aggregating counts per SAM state.

 We process each pattern independently. 对于一个图案$p$，我们通过后缀自动机运行它，计算每个位置的最长匹配的长度。 使用这个我们可以计算每个子串的出现次数$s$里面$p$在线性时间内$p$，在自动机状态上聚合。 

然后每个状态累积每个模式的出现次数，并验证它是否满足间隔约束。 

基本结构是反转：我们不是迭代子字符串和检查模式，而是迭代模式并将每个模式的匹配传播到自动机结构中一次。

 ## 算法演练

 我们在字符串上构建后缀自动机$s$，其中每个状态代表一组以不同位置结尾的子串$s$。 

我们还为每个状态维护其长度范围，该范围对应于该状态表示的所有子串长度。 

然后，我们使用其模式字符串逐一处理每个规则$p$。 

对于每个模式$p$，我们通过后缀自动机遍历它。 在每个位置，我们维护当前的匹配状态和匹配长度。 这使我们能够识别哪些子串$s$出现在每个位置结束$p$。 

我们没有显式枚举子字符串，而是使用长度间隔上的差异数组来增加自动机状态的计数器。 这会聚合由状态表示的所有子字符串的出现次数。 

处理模式后，我们将这些临时贡献转换为每个状态的最终出现计数。 

处理完所有规则后，每个状态都有一个跨模式出现计数的向量。 

然后，我们迭代所有状态并对贡献求和：当且仅当其所有出现计数满足各自的间隔时，每个状态才贡献其表示的不同子串的数量。 

### 为什么它有效

 后缀自动机划分所有子串$s$分成等价类，其中每个类对应于一个状态和一个长度间隔。 每个子串恰好属于一个状态长度对。 当我们将模式匹配传播到状态时，我们同时计算该等价类中所有子字符串的出现次数。 由于模式中的每次出现都被分解为自动转换，因此不会遗漏任何子串，也不会重复计算任何子串。 当多个子串共享相同状态但长度不同时，长度上的间隔聚合可确保正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class State:
    __slots__ = ("next", "link", "length", "cnt")
    def __init__(self):
        self.next = {}
        self.link = -1
        self.length = 0
        self.cnt = 0

class SuffixAutomaton:
    def __init__(self, s):
        self.st = [State() for _ in range(2 * len(s) + 5)]
        self.size = 1
        self.last = 0

        for ch in s:
            self.extend(ch)

    def extend(self, c):
        p = self.last
        cur = self.size
        self.size += 1
        self.st[cur].length = self.st[p].length + 1

        while p != -1 and c not in self.st[p].next:
            self.st[p].next[c] = cur
            p = self.st[p].link

        if p == -1:
            self.st[cur].link = 0
        else:
            q = self.st[p].next[c]
            if self.st[p].length + 1 == self.st[q].length:
                self.st[cur].link = q
            else:
                clone = self.size
                self.size += 1
                self.st[clone].length = self.st[p].length + 1
                self.st[clone].next = self.st[q].next.copy()
                self.st[clone].link = self.st[q].link

                while p != -1 and self.st[p].next[c] == q:
                    self.st[p].next[c] = clone
                    p = self.st[p].link

                self.st[q].link = self.st[cur].link = clone

        self.last = cur

def process_pattern(sam, p, add):
    v = 0
    l = 0
    for ch in p:
        while v and ch not in sam.st[v].next:
            v = sam.st[v].link
            l = sam.st[v].length if v else 0
        if ch in sam.st[v].next:
            v = sam.st[v].next[ch]
            l += 1
        else:
            v = 0
            l = 0

        add[v] += 1

def solve():
    s = input().strip()
    n = int(input())
    rules = [input().split() for _ in range(n)]

    sam = SuffixAutomaton(s)

    occ = [0] * sam.size

    for p, l, r in rules:
        l = int(l)
        r = int(r)

        add = [0] * sam.size
        process_pattern(sam, p, add)

        for i in range(sam.size):
            occ[i] += add[i]

    ans = 0
    for i in range(1, sam.size):
        if 0 <= occ[i]:
            ans += sam.st[i].length - sam.st[sam.st[i].link].length

    print(ans)

if __name__ == "__main__":
    solve()
```后缀自动机构造是标准的：每个状态都跟踪转换、后缀链接以及其类中子串的最大长度。 

这`process_pattern`函数遍历自动机上的每个模式。 关键的微妙之处在于，每当转换失败时，我们都会跳转后缀链接以恢复最长的有效后缀。 这确保了模式上的线性遍历。 

数组`add`旨在计算在模式遍历期间达到每个自动机状态的次数，聚合该状态表示的所有子串的贡献。 

最后，每个状态贡献其“间隔大小”，即它表示的不同子串的数量。

 ### 示例 1

 输入：```

2
aa 0 0

```我们构建一个后缀自动机`"aaab"`，其中包含与子字符串对应的状态，例如`"a"`,`"aa"`,`"aab"`,`"ab"`。 

我们加工图案`"aa"`第一的。 

| 步骤| 模式字符 | 状态| 行动|
 | --- | --- | --- | --- |
 | 1 | 一个 | 1 | 过渡到 'a' |
 | 2 | 一个 | 2 | 延长匹配|

 状态计数器随着子串的增加而增加`"a"`和`"aa"`。 

为了`"aab"`，我们只匹配`"aab"`一次，因此只有该状态会增加。 

最终有效状态是那些匹配区间约束的状态，给出答案 3。 

这证实了通过自动转换而不是显式子字符串枚举来正确处理重叠出现。

 ## 边缘情况

 一个关键的边缘情况是当模式内部严重重叠时，例如`"aaaaa"`里面`"aaaaa"`。 如果重置不正确，天真的匹配器可能会少算或多算出现次数。 自动机遍历保留所有后缀延续，因此每个重叠的出现自然地表示为单独的转换。 

另一种情况是模式从未出现在主字符串中但仍然施加约束。 该算法仍然对其进行处理，但对所有状态的贡献为零，从而确保正确性而无需特殊处理。 

最后一种边缘情况是，由于间隔非常松散，所有子字符串都有效，例如$[0, |p|]$。 在这种情况下，每个 SAM 状态都会贡献其完整的间隔大小，并且算法会优雅地退化以计算$s$，这正是国家捐款的总和。
