 ## 解决方案
 ## 问题理解

 我们有一个`n × m`网格。 每个单元格包含一只鞋子，并且每双鞋的编号在整个网格中恰好出现两次。 

当属于每双的两只鞋占据相邻的单元时，配置被认为是整洁的。 相邻是共享边，而不是角。 

我们可以在牢房之间移动鞋子。 如果鞋子没有保留在原来的单元格中，则视为已移动。 任务是找到必须改变位置的最少鞋子数量，以便最终排列整齐。 

网格最多包含`80 × 80 = 6400`细胞。 由于每对恰好出现两次，因此最多有`3200`不同的对。 

对所有可能的最终安排进行强力搜索是没有希望的。 即使枚举网格中所有的多米诺骨牌，其规模也是天文数字。 这些约束立即表明解决方案必须利用网格结构并将问题简化为多项式时间图问题。 

棘手的部分是我们没有被要求构建最终的安排。 我们只需要最少数量的能移动的鞋子。 这让我们能够思考哪些鞋子可以留在原处。 

考虑这个小例子：```
1 1
```这对已经相邻。 正确答案是`0`。 

总是移动每双鞋中的一只鞋的粗心解决方案会错误地输出`1`。 

另一个有趣的例子是：```
1 2
2 1
```每个数字的两次出现都是对角的，因此两对都不是相邻的。 

正确答案是`2`。 

一双鞋中的一只`1`可以留下来，一双鞋`2`可以留下来，另外两只鞋子必须移动。 

一个常见的错误是认为每双放错位置的鞋子都需要移动两只鞋子。 

第三种边缘情况是：```
1 2 3
1 2 3
```每对已经垂直相邻。 答案是`0`。 

首先贪婪地匹配水平邻居的解决方案将错过最佳排列。 

## 方法

 蛮力观点是决定哪些相邻单元将在最终整齐的排列中形成对。 

整齐的排列将整个网格划分为相邻的单元对。 在图语言中，我们正在寻找网格图的完美匹配。 

假设我们以某种方式选择了这样一对细胞。 

取一条连接两个相邻单元格的匹配边。 

如果两个单元格已经包含相同的编号，则两只鞋都可以保留在原处。 这双鞋里面的鞋子不需要移动。 

如果两个单元格包含不同的数字，则最多可以留下一只鞋子。 一个单元可以保留当前的鞋子并稍后接收其伙伴，而另一只鞋子必须离开。 对于那双匹配的鞋子来说，完全相同的一只鞋子的移动是不可避免的。 

这一观察彻底改变了问题。 

我们不需要全局推理鞋子的身份，而只需要知道匹配边的两个端点当前是否包含相同的数字。 

对于匹配的边：```
same numbers     -> cost 0
different numbers -> cost 1
```移动鞋子的总数等于所有匹配边上这些成本的总和。 

现在问题变成：

 以最小的总成本找到网格图的完美匹配。 

网格图是二分图。 像棋盘一样给单元格上色。 

每条边都连接一个黑色单元和一个白色单元。 

我们构建一个二分图：

 - 来源 → 每个黑色单元格，容量 1，成本 0。 
- 每个白色单元→水槽，容量1，成本0。 
- 相邻的黑色和白色单元格之间：

 - 容量1
 - 如果数量相等则成本为 0
 - 否则花费 1

 一个流单元选择一条匹配的边。 

因为每个单元的容量为 1，所以最大流量为`nm/2`完全对应于网格的完美匹配。 

最小成本的完美匹配给出了最少的搬鞋数量。 这种减少是关键的见解。 它将尴尬的重排问题转化为标准的最小成本最大流问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力配对 | 指数| 指数| 太慢了 |
 | 网格图上的最小成本完美匹配| 多项式 | O(V + E) | 已接受 |

 ## 算法演练

 1. 将网格涂成棋盘图案。 
2. 为每个单元创建一个图顶点。 
3. 添加源和接收器。 
4. 将电源连接到每个有容量的黑色电池`1`和成本`0`。 
5. 将每个白色电池连接到带有容量的水槽`1`和成本`0`。 
6. 对于每对相邻的黑白电池，添加容量边缘`1`。 

如果两个单元格包含相同的数字，则边成本为`0`。 

否则边缘成本为`1`。 
7. 运行最小成本最大流并准确发送`nm/2`流量单位。 
8. 流算法返回的最小成本就是答案。 

### 为什么它有效

 每个流单元选择一个相邻的黑白对。 由于每个电池都有容量`1`，最大流量尺寸`nm/2`每个单元格都匹配一次。 这正是网格图的完美匹配。 

对于任何匹配的细胞对，对答案的贡献是：

 -`0`如果两个单元格已包含相同的对号。 
-`1`否则。 

这些成本恰好等于必须离开这两个牢房的最小鞋子数量。 

对所有匹配的鞋子进行求和，得出完美匹配所需移动鞋子的最少数量。 

由于最小成本最大流算法会检查所有完美匹配并选择总成本最小的匹配，因此得到的成本正是最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class MinCostMaxFlow:
    class Edge:
        __slots__ = ("to", "rev", "cap", "cost")

        def __init__(self, to, rev, cap, cost):
            self.to = to
            self.rev = rev
            self.cap = cap
            self.cost = cost

    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, u, v, cap, cost):
        fwd = self.Edge(v, len(self.g[v]), cap, cost)
        rev = self.Edge(u, len(self.g[u]), 0, -cost)
        self.g[u].append(fwd)
        self.g[v].append(rev)

    def min_cost_flow(self, s, t, need):
        n = self.n
        INF = 10 ** 18

        flow = 0
        cost = 0
        pot = [0] * n

        while flow < need:
            dist = [INF] * n
            parent_v = [-1] * n
            parent_e = [-1] * n

            import heapq
            pq = [(0, s)]
            dist[s] = 0

            while pq:
                d, v = heapq.heappop(pq)
                if d != dist[v]:
                    continue

                for ei, e in enumerate(self.g[v]):
                    if e.cap <= 0:
                        continue

                    nd = d + e.cost + pot[v] - pot[e.to]
                    if nd < dist[e.to]:
                        dist[e.to] = nd
                        parent_v[e.to] = v
                        parent_e[e.to] = ei
                        heapq.heappush(pq, (nd, e.to))

            if dist[t] == INF:
                break

            for i in range(n):
                if dist[i] < INF:
                    pot[i] += dist[i]

            add = need - flow
            v = t

            while v != s:
                pv = parent_v[v]
                pe = parent_e[v]
                add = min(add, self.g[pv][pe].cap)
                v = pv

            v = t
            while v != s:
                pv = parent_v[v]
                pe = parent_e[v]
                e = self.g[pv][pe]

                e.cap -= add
                self.g[v][e.rev].cap += add

                v = pv

            flow += add
            cost += add * pot[t]

        return flow, cost

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    cells = n * m
    s = cells
    t = cells + 1

    mcmf = MinCostMaxFlow(cells + 2)

    def id_of(r, c):
        return r * m + c

    dirs = ((1, 0), (-1, 0), (0, 1), (0, -1))

    black_count = 0

    for r in range(n):
        for c in range(m):
            v = id_of(r, c)

            if (r + c) & 1:
                black_count += 1
                mcmf.add_edge(s, v, 1, 0)

                for dr, dc in dirs:
                    nr = r + dr
                    nc = c + dc

                    if 0 <= nr < n and 0 <= nc < m:
                        u = id_of(nr, nc)
                        cost = 0 if a[r][c] == a[nr][nc] else 1
                        mcmf.add_edge(v, u, 1, cost)
            else:
                mcmf.add_edge(v, t, 1, 0)

    _, answer = mcmf.min_cost_flow(s, t, black_count)
    print(answer)

if __name__ == "__main__":
    solve()
```图形构造遵循棋盘着色。 每个黑色单元格必须与一个相邻的白色单元格精确匹配，并且每个白色单元格必须精确匹配一次。 

邻接边上的成本编码匹配对是否已包含相同的数字。 这就是整个优化目标。 

该实现使用具有约翰逊势的标准连续最短增广路径算法。 在原始图中，所有成本都是非负的，但剩余边会引入负成本，因此势能保持 Dijkstra 有效。 

一个常见的实现错误是忘记只应添加黑白邻接边。 如果两个方向都添加为正常图边，则匹配约束将被破坏。 

另一个容易犯的错误是请求错误的流量。 所需的流量正是黑色单元的数量，等于`nm/2`。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(F·E log V) | O(F·E log V) | 连续最短增广路径|

 这里`V = nm + 2`,`E = O(nm)`， 和`F = nm/2`。

import sys
import io

def run(inp: str) -> str:
    from heapq import heappush, heappop

    input_data = io.StringIO(inp)

    def input():
        return input_data.readline()

    class MCMF:
        class Edge:
            __slots__ = ("to", "rev", "cap", "cost")

            def __init__(self, to, rev, cap, cost):
                self.to = to
                self.rev = rev
                self.cap = cap
                self.cost = cost

        def __init__(self, n):
            self.g = [[] for _ in range(n)]
            self.n = n

        def add(self, u, v, cap, cost):
            a = self.Edge(v, len(self.g[v]), cap, cost)
            b = self.Edge(u, len(self.g[u]), 0, -cost)
            self.g[u].append(a)
            self.g[v].append(b)

        def flow(self, s, t, need):
            n = self.n
            pot = [0] * n
            cost = 0
            flow = 0
            INF = 10**18

            while flow < need:
                dist = [INF] * n
                pv = [-1] * n
                pe = [-1] * n
                dist[s] = 0

                pq = [(0, s)]

                while pq:
                    d, v = heappop(pq)
                    if d != dist[v]:
                        continue

                    for i, e in enumerate(self.g[v]):
                        if e.cap <= 0:
                            continue

                        nd = d + e.cost + pot[v] - pot[e.to]
                        if nd < dist[e.to]:
                            dist[e.to] = nd
                            pv[e.to] = v
                            pe[e.to] = i
                            heappush(pq, (nd, e.to))

                for i in range(n):
                    if dist[i] < INF:
                        pot[i] += dist[i]

                add = need - flow
                v = t

                while v != s:
                    add = min(add, self.g[pv[v]][pe[v]].cap)
                    v = pv[v]

                v = t
                while v != s:
                    e = self.g[pv[v]][pe[v]]
                    e.cap -= add
                    self.g[v][e.rev].cap += add
                    v = pv[v]

                flow += add
                cost += add * pot[t]

            return cost

    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    N = n * m
    s = N
    t = N + 1

    g = MCMF(N + 2)

    def idx(r, c):
        return r * m + c

    blacks = 0

    for r in range(n):
        for c in range(m):
            v = idx(r, c)

            if (r + c) & 1:
                blacks += 1
                g.add(s, v, 1, 0)

                for dr, dc in ((1,0),(-1,0),(0,1),(0,-1)):
                    nr = r + dr
                    nc = c + dc
                    if 0 <= nr < n and 0 <= nc < m:
                        g.add(v, idx(nr, nc), 1,
                              0 if a[r][c] == a[nr][nc] else 1)
            else:
                g.add(v, t, 1, 0)

    return str(g.flow(s, t, blacks))

 ## 边缘情况

 考虑：```
2 1
1
1
```唯一可能的匹配是同时使用两个单元格。 它们的值相等，因此匹配边有成本`0`。 算法返回`0`，这是正确的。 

现在考虑：```
2 2
1 2
2 1
```每个相邻对都包含不同的数字。 任何完美匹配都由两个不匹配的边组成，每个边都会产生成本`1`。 最小成本是`2`，所以答案是`2`。 

最后：```
2 3
1 2 3
1 2 3
```最小成本完美匹配使用三个垂直边。 三者都有成本`0`。 流量成本为`0`，意味着鞋子不需要移动。 该算法自然地发现了这一点，因为在构造最小成本完美匹配时总是首选零成本边缘。
