 ## 解决方案
 ## 问题理解

 我们得到一个网格，其中每个单元格都有一个地形值，可以解释为在该位置安全操作所需的高度。 直升机从某个单元格开始，必须穿过网格，在四个方向上改变单元格。 关键的难点在于移动不是自由的：直升机必须保持一定的飞行高度，改变高度会消耗燃料，而水平移动还取决于当前高度是否足以满足当前和目的地单元格的需要。 

任务是计算在该网格上从起始配置移动到目标配置所需的最小燃料，同时考虑单元高度以及上升、下降和飞行的成本模型施加的约束。 

网格尺寸足够大，任何独立处理每个位置的解决方案都是不够的。 如果我们将每个单元格和高度视为一个状态，则状态空间大致与网格大小和可能高度的乘积成正比。 这立即表明，除非我们找到结构简化，否则所有状态上的朴素最短路径或动态规划将太慢。 

直接解释得出一个图表，其中每个节点都是一对位置和高度。 即使有适度的界限，这也会爆炸到类似 O(n m A) 的程度，并且状态之间的转换可能会引入 A 的另一个因素。这使得朴素的最短路径方法不可行，除非 A 非常小或转换经过严格优化。 

当在高度不同的两个相邻单元格之间移动时，会出现微妙的边缘情况。 一种幼稚的方法可能会假设您总是在移动之前单独支付到达更高高度的全部成本，但实际上，最佳行为通常涉及在移动过程中调整高度，而不是在移动之前。 例如，如果两个相邻单元格需要高度 1 和 100，则与协调调整相比，在移动之前完全升高高度是浪费的。 

当路径重新访问行或列时，会出现另一个重要的失败情况。 一些部分 DP 方法假设单调移动，但当允许横向移动时，最佳路径可能会暂时增加成本，以减少未来的高程成本。 

## 方法

 蛮力思想对每种可能的直升机配置进行了建模：每个状态都是位置和当前高度的三重。 从每个状态，我们模拟三种类型的转换：向上或向下改变高度，如果当前高度对于两个端点来说都足够高，则移动到相邻单元格。 这可以正确地对问题进行建模，因为它显式地编码了所有约束。 

然而，该图有 O(n m A) 个状态，每个状态都可以转换到 O(A + 4) 个其他状态。 即使我们使用 0-1 BFS 或 Dijkstra 变体，转换总数也会变为 O(n m A^2)，这对于典型约束来说太大了，除非 A 非常小。 

关键的观察结果是，细胞之间的运动永远不会受益于任意的中间高度。 如果我们从单元格 u 移动到单元格 v，并且所需的安全高度为 max(au, av)，那么高于此高度的任何高度只会增加成本，而不会提高可行性。 任何更高的航段都可以分解为“下降、移动、上升”，而不会增加总成本。 这意味着最佳路径只需要考虑每次移动所需的最低高度。 

一旦高度与边相关而不是每个状态自由浮动，问题就变成了变换图上的最短路径问题。 我们不再连续跟踪任意高度； 相反，我们只考虑边缘引起的必要高度变化。 

这种减少使我们能够从分层状态图转移到更小的图，其中成本与单元之间的转换相关，而不是与连续的高度状态相关。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | （单元格，高度）| 全状态最短路径 O(n m A^2) | O(n m A^2) | O(n m A) | 太慢了 |
 | 受限高度转换的优化图表 | O(n·m log(n·m)) | O(n·m) | 已接受 |

 ## 算法演练

 1. 将每个网格单元建模为图中的节点，但不直接附加任意高度状态。 相反，将运动解释为边缘过程，其中每个边缘都有由其端点确定的最小所需飞行高度。 这将连续的高度决策减少为离散的边缘成本。 
2. 对于每对相邻单元，计算最小安全飞行高度作为其地形值的最大值。 该值表示直升机在没有额外约束的情况下可以安全穿越该边缘的最低高度。 
3. 将每个动作解释为由两个概念部分组成：调整当前单元格内的高度，然后在所需的边缘高度执行飞行。 移动的成本恰好成为该边缘所需的高度，因为任何上升或下降都可以吸收到相同的成本核算中，而不会损失最优性。 
4. 构建一个图，其中顶点表示位置（或者如果需要方向约束则稍微丰富的状态变体），边表示有效移动，其权重等于之前计算的所需飞行高度。 这将问题转化为最短路径问题。 
5. 从起始状态运行 Dijkstra 算法。 每个放松步骤对应于选择下一个要进入的单元格并支付相应的最低安全高度成本。 
6. 维护每个节点的距离并使用优先级队列更新它们。 由于边权重是非负的，Dijkstra 正确地产生了最优解。 

### 为什么它有效

 正确性依赖于将高度行为压缩为边缘权重。 任何具有任意高度变化的可行轨迹都可以转换为每次移动都在该移动所需的最低高度上执行的轨迹，而不会增加总成本。 这消除了冗余的高空段，并确保仅位置上的搜索空间就足够了。 由于所有剩余决策都是具有非负权重的局部边缘选择，因此 Dijkstra 的贪婪选择保留了最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    INF = 10**18
    dist = [[INF] * m for _ in range(n)]
    dist[0][0] = a[0][0]

    pq = [(a[0][0], 0, 0)]

    dirs = [(1,0), (-1,0), (0,1), (0,-1)]

    while pq:
        d, x, y = heapq.heappop(pq)
        if d != dist[x][y]:
            continue

        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m:
                cost = max(a[x][y], a[nx][ny])
                nd = d + cost
                if nd < dist[nx][ny]:
                    dist[nx][ny] = nd
                    heapq.heappush(pq, (nd, nx, ny))

    print(dist[n-1][m-1])

if __name__ == "__main__":
    solve()
```该实现在网格单元上使用 Dijkstra，其中每个边权重是在两个相邻单元之间遍历所需的最小安全高度。 优先级队列确保我们始终扩展当前最便宜的可达单元。 

关键的微妙之处在于边缘权重的定义：它不仅是目标单元格的高度，而且是两个端点的最大值，因为在飞行过程中必须安全地覆盖两个端点。 

我们还避免任何显式的高度跟踪，这是保持状态空间在网格大小上线性的关键减少。

 ## 边缘情况

 单单元网格测试算法是否正确地将起点视为目的地，而没有不必要的转换。 距离直接从像元值初始化，因此不会发生松弛。 

具有被低值包围的非常大峰值的网格测试算法是否正确地选择避免多次支付峰值成本的路径。 由于边权重使用最大端点数，因此每次遍历峰值时只需支付一次。 

严格递增的网格测试算法在单调条件下是否表现一致。 在这种情况下，最短路径被迫遵循唯一可行的方向，并且 Dijkstra 以可预测的顺序处理节点，而无需替代松弛。
