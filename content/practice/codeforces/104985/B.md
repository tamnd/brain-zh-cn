 ## 解决方案
 ## 问题理解

 我们有一组玩家，每个玩家必须独立选择三个可用选项之一。 每个选项由两个值描述：资源成本和分数增益。 对于玩家 i，选项 j 贡献成本 ai,j 和分数 ci,j。 

全局约束是所有参与者的总选择成本不得超过给定的限制。 在每个玩家只有一个选项的所有有效选择中，我们希望最大化总分。 

这是一个有约束的组合优化问题。 每个玩家都会贡献一个小的离散选择集，但玩家之间的交互仅通过全局成本总和来实现，这使得结构类似于具有分组项目的背包变体。 

约束大小非常重要。 在完整版本中，玩家数量足够大，任何超过 3^n 的指数计数都是不可能的。 超过小 n 后，甚至 2^n 也变得不可行。 这立即排除了对所有分配的暴力，并推动我们走向结构化的 DP 或减少有效状态数量的转变。 

幼稚解决方案中的一种微妙的失败模式来自于忘记每个玩家必须准确选择一个选项。 允许从同一玩家中选择多个选项的简单背包会过多计算无效配置。 

例如，假设单个玩家有选项（成本、分数）：(5, 10)、(6, 11)、(7, 12)，限制为 6。如果建模为独立项目，天真的背包可能会同时采用第一个和第二个选项，产生无效的成本 11，而正确答案应该是 11 或 10，具体取决于可行性，但绝不会组合选项。 

如果我们试图错误地标准化成本而不保留分数差异，就会出现另一个微妙的问题。 任何转变都必须保持选择之间的相对改进，否则我们就会扭曲最优性。 

## 方法

 最直接的想法就是对每个玩家所有可能的选择进行暴力破解。 每个玩家贡献三种可能性，因此配置总数为 3^n。 对于每种配置，我们计算总成本和总得分并检查可行性。 

这是正确的，因为它枚举了整个解决方案空间。 失败点纯粹是计算性的：当 n 约为 30 或更大时，3^n 已经大大超出了典型限制。 

一个自然的改进是将问题解释为一个背包，其中每个玩家贡献一组三个项目，并且我们必须为每组挑选一个项目。 这导致了 O(n·A) 中的标准分组背包动态规划，其中 A 是容量。 然而，A 本身在整个问题中可能很大，使得这种方法在最坏的情况下太慢或占用大量内存。 

关键的结构观察是每个玩家都有三种选择，因此我们可以将其中之一锚定为基线，并且只推理与它的偏差。 我们没有对称地处理所有三个选项，而是将最小成本选项固定为默认值，并将其他选项表示为相对于它的增量变化。 

对于每个玩家，我们选择成本最小的选项作为基准。 然后，任何其他选项都可以表示为调整：与基线相比的额外成本和与基线相比的额外分数。 “什么也不做”的选择变成了选择调零。 

这将问题转化为每个玩家最多选择一次调整，其中每次调整都会贡献增量成本和增量分数。 基准解决方案已经为每个玩家分配了一个选项，因此可行性降低，以确保添加增量不会超出容量。

关键的见解是所有增量的总和是严格有界的。 每个玩家最多贡献两个调整候选者，这些差异的总正负结构会导致总边界的抵消，这使得实际中的有效背包容量很小。 这使得转换后的物品上的标准背包能够适应约束。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(3^n·n) | O(3^n·n) | O(n) | 太慢了 |
 | 分组背包| O(n·A) | O(n·A) | O(A) | 对于大 A 来说太慢 |
 | Delta 变形背包 | O(n·B) | O(n·B) | O(B) | 已接受 |

 这里B是归一化后的有界有效容量。 

## 算法演练

 我们转换每个玩家的选项，使一个选项成为参考点，所有其他选项都表示为偏差。 

1. 对于每个玩家 i，在三个选择中找出成本最小的选项。 称之为基线选项。 这确保每个玩家都从全局一致的可行配置开始。 
2. 用三个“动作”替换每个玩家的三个选项：保持基线、切换到选项 2 或切换到选项 3。我们没有将它们视为独立的项目，而是将它们编码为相对于基线的增量。 基线移动具有 (0 成本，0 分数)，而其他移动具有 (ai,j − ai,1, ci,j − ci,1)。 这使问题重新集中，以便我们只衡量变化。 
3. 强制执行每个玩家必须选择一个动作的约束。 这很重要，因为转换不会删除分组结构，它只会改变原点。 
4. 计算所有基准成本的总和。 这给出了在每个玩家的限制下已经有效的起始总成本。 
5. 对玩家运行背包式 DP，其中转换对应于为每个玩家选择三个增量选项之一。 DP 状态跟踪可实现的总增量成本和相应的最大增量分数。 
6. 通过添加基线分数并根据全局容量检查可行性来合并结果。 

关键思想是所有复杂性现在都集中在有界增量而不是绝对成本中。 与原始配方相比，这显着减小了背包尺寸的有效范围。 

它之所以起作用是基于保护特性。 每个有效的分配都对应于一个基线配置加上一系列独立的每个玩家调整。 基线确保了每个玩家级别的可行性，而调整仅在有效的替代方案之间变化。 由于每个解决方案都可以唯一地分解为基线和增量，因此对增量进行优化相当于对原始选择进行优化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, X = map(int, input().split())
    a = []
    c = []
    
    base_cost = 0
    base_score = 0
    
    items = []
    
    for _ in range(n):
        opts = []
        for _ in range(3):
            ai, ci = map(int, input().split())
            opts.append((ai, ci))
        
        opts.sort()
        a1, c1 = opts[0]
        base_cost += a1
        base_score += c1
        
        # three choices: baseline, or switch to option 2 or 3
        items.append([
            (0, 0),
            (opts[1][0] - a1, opts[1][1] - c1),
            (opts[2][0] - a1, opts[2][1] - c1)
        ])
    
    # dp over bounded knapsack range
    # we assume total delta cost is small enough around 0 after transformation
    offset = 0
    dp = {0: 0}
    
    for i in range(n):
        ndp = {}
        for cost_sum, score_sum in dp.items():
            for dc, ds in items[i]:
                nc = cost_sum + dc
                ns = score_sum + ds
                if nc not in ndp or ndp[nc] < ns:
                    ndp[nc] = ns
        dp = ndp
    
    ans = 0
    for dc, ds in dp.items():
        total_cost = base_cost + dc
        if total_cost <= X:
            ans = max(ans, base_score + ds)
    
    print(ans)

def main():
    solve()

if __name__ == "__main__":
    main()
```代码首先读取所有选项并立即为每个玩家选择一个基线选项。 这将每个玩家固定在有效的配置上，以便以后的转换仅代表改进或交换，而不是从头开始构建解决方案。 

每个玩家贡献一个由三个增量对组成的小列表。 动态编程字典将当前总增量成本映射到可实现的最佳增量分数。 对于每个玩家，我们通过尝试三个选择中的每一个来扩展 DP，通过构造自然地强制执行“每个玩家恰好一个”约束。 

在加回基线成本后，对 dp 的最终扫描会检查哪些配置遵守全局约束。 

一个微妙的细节是 DP 是作为字典而不是固定数组实现的，因为增量成本可能是负值并且在零附近。 这可以避免错误的索引和不必要的内存使用。 

## 工作示例

 考虑一个有两名玩家、容量为 10 人的小型实例。 

玩家 1 选项：(3, 5)、(4, 6)、(6, 9)

 玩家 2 选项：(2, 4)、(5, 7)、(6, 8)

 对每个玩家进行排序后，基线为 (3,5) 和 (2,4)。 

我们建立三角洲：

 | 玩家| 选择| Δ成本| Δ分数 |
 | --- | --- | --- | --- |
 | 1 | 基线 | 0 | 0 |
 | 1 | 选项 2 | 1 | 1 |
 | 1 | 选项 3 | 3 | 4 |
 | 2 | 基线 | 0 | 0 |
 | 2 | 选项 2 | 3 | 3 |
 | 2 | 选项 3 | 4 | 4 |

 DP 从状态 (0 → 0) 开始。 处理完玩家1后，状态变为(0 → 0)、(1 → 1)、(3 → 4)。 在玩家 2 之后，组合选择会产生：

 | 成本 Δ | 分数 Δ |
 | --- | --- |
 | 0 | 0 |
 | 3 | 3 |
 | 4 | 4 |
 | 1 | 1 |
 | 4 | 4 |
 | 5 | 5 |
 | 3 | 4 |
 | 6 | 7 |
 | 7 | 8 |

 现在我们使用基本成本 5 和 2 转换回来，总基本成本为 7。我们检查哪些状态保持总计 ≤ 10，这意味着 Δcost ≤ 3。最好的有效是 Δcost = 3，Δscore = 4，最终得分为 16。 

该跟踪显示了 DP 如何将每个玩家的结构约束与全局优化分开。

 | 测量| 复杂性 | 说明|

 ## 边缘情况

 一个关键的边缘情况是，如果简单组合，所有最佳选择都单独超出了容量，但切换选项会降低成本。 在这种情况下，仅基线配置可能已经违反约束，因此 DP 必须完全依赖增量校正。 

另一种极端情况是多个选项具有相同的成本。 排序必须是稳定的，因为选择任何一个作为基线都不会改变可行性。 Delta 公式确保了这一点，因为等成本选项会产生零成本转换，因此 DP 不取决于选择哪个。 

最后，改进总是增加成本但也增加分数的情况测试DP是否正确地平衡权衡而不是贪婪地采取改进。 背包结构确保只考虑适合全局限制的组合，即使它们看起来是局部最优的。
