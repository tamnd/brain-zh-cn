 ## 解决方案
 ## 问题理解

 我们得到了一系列不同的值，这些值已经按升序排序。 从此序列的任何连续段中，只要元素满足局部凸性条件，我们就可以重复删除元素：如果内部元素与其两个邻居相比不是“太高”，特别是如果它最多是邻居的平均值，则可以删除内部元素。 

每次删除后，序列都会收缩并形成新的邻接关系，这可能会解锁进一步的删除。 对于每个查询段，任务是确定在以任意顺序应用这些删除后可以保留的最小可能元素数，直到不再存在有效的删除。 

输入由多个测试用例组成。 每个测试用例都会给出一个递增数组，然后对子数组进行多个查询。 每个查询都是独立的，并要求在删除规则下该子数组可达到的最小最终大小。 

约束结构表明​​所有测试用例的总数组大小和查询数量很大，约为数十万。 任何尝试直接模拟删除的解决方案都会太慢，因为每次删除都可能花费线性时间来维护结构，并且在最坏的情况下，即使单个查询也可能退化为二次行为。 

关键的边缘情况与无效输入无关，而是与删除规则如何与本地模式交互有关。 

直觉可能失败的一个小例子是严格凸三元组，例如`[1, 2, 4]`。 中间元素`2`满足`2*2 <= 1 + 4`，因此可以将其删除，留下`[1, 4]`，并且无法进一步删除。 一个天真的假设，即只有端点很重要，会错误地表明所有内部点都是可移除的，或者根据解释，没有任何东西是可移除的。 

另一个边缘情况是近乎线性的进展，例如`[1, 3, 5, 7, 9]`。 许多内部点很早就满足删除条件，但是一旦删除一个，剩余的结构可能会以非明显的方式解锁或阻止未来的删除。 这使得贪婪局部推理在不跟踪全局凸包结构的情况下是不够的。 

## 方法

 暴力解决方案将独立模拟每个查询。 对于给定的子数组，我们重复扫描任何索引`i`这样`2 * B[i] <= B[i-1] + B[i+1]`，删除它，然后重新启动或更新邻居。 每次删除都需要更新邻接关系并可能重新扫描阵列。 

在最坏的情况下，单个查询的长度`k`可以执行`O(k)`删除，并且每次删除可能会花费`O(k)`扫描工作量。 这导致`O(k^2)`每个查询。 和`k`最多`5 × 10^4`在许多查询中，这远远超出了可行的限制。 

关键的观察结果是，删除条件正是一个点位于其邻居之间的线段之上或之下的条件。 从几何角度来看，这意味着当解释为点时，我们会重复删除不属于序列上凸包的点`(i, a[i])`。 

由于数组索引严格递增且值严格递增，因此该结构成为单调链，其中最终剩余元素与线段中点的凸包完全对应。 每次删除都会删除一个违反凸性的点，并且该过程将继续，直到只剩下外壳顶点。 

这将问题从动态删除转变为静态计算：对于每个查询，我们只需要该区间内点的上凸包的大小。 由于 x 坐标是固定的并且不断增加，因此这简化为在一维的线段上维护凸包，这可以使用线段树或具有包合并的分而治之预计算来有效地解决。 

标准方法是对于每个线段树节点，按排序顺序存储其范围的凸包。 合并两个节点对应于合并两个凸链，这可以在所得外壳的大小的线性时间内完成。 查询范围收集`O(log n)`外壳并合并它们，产生最终的外壳，其大小就是答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 每次查询 O(k²) | O(k) | 太慢了|
 | 线段树凸包合并 | 每次查询 O(log n · h) | O(n log n) | O(n log n) | 已接受 |

 ## 算法演练

 1. 对待每个元素`a[i]`作为一个点`(i, a[i])`。 这将问题转换为几何结构，其中删除对应于删除非凸点。 
2. 在数组上构建一棵线段树，其中每个节点按递增顺序存储其区间的凸包`i`。 使用类似堆栈的合并规则将船体维护为单调链。 这是可行的，因为索引已经排序，所以我们只需要在一个方向上强制凸性。 
3. 要合并两个船体，请将右船体附加到左船体上，并重复删除倒数第二个点，因为它与相邻的船体违反了凸性。 该条件符合删除规则，因为当点位于凹转弯内时，该点恰好可被删除。 
4. 查询`[l, r]`，收集覆盖该区间的所有线段树节点并将它们的外壳合并为单个外壳。 这个合并船体的大小就是答案。 
5. 输出每个查询的外壳大小。 

关键思想是原始过程中的删除以仅取决于最终凸结构的方式进行交换，因此我们永远不需要模拟删除的顺序。 

### 为什么它有效

 不变量是，在任何序列的有效删除之后，剩余的点总是相对于不等式形成凸链`2 * a[i] > a[i-1] + a[i+1]`。 该过程删除的任何点都不能成为线段的任何凸表示的一部分，因为它位于最终配置中两个幸存邻居之间的线段之上。 相反，凸包中保留的每个点都没有有效的删除序列来删除它而不破坏剩余结构的凸性。 这种对应关系确保最终状态是唯一的并且等于线段的凸包。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def bad(p1, p2, p3):
    # check if p2 should be removed (not convex)
    # equivalent to: 2*p2 <= p1 + p3
    return (p2[1] * 2) <= (p1[1] + p3[1])

def merge(left, right):
    # merge two convex chains
    res = left[:]
    for p in right:
        res.append(p)
        while len(res) >= 3 and bad(res[-3], res[-2], res[-1]):
            res.pop(-2)
    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.data = [[] for _ in range(2 * self.size)]
        
        for i in range(self.n):
            self.data[self.size + i] = [(i, arr[i])]
        
        for i in range(self.size - 1, 0, -1):
            self.data[i] = merge(self.data[2 * i], self.data[2 * i + 1])
    
    def query(self, l, r):
        l += self.size
        r += self.size
        left_hull = []
        right_hull = []
        
        while l <= r:
            if l % 2 == 1:
                left_hull = merge(left_hull, self.data[l])
                l += 1
            if r % 2 == 0:
                right_hull = merge(self.data[r], right_hull)
                r -= 1
            l //= 2
            r //= 2
        
        return merge(left_hull, right_hull)

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        st = SegTree(a)
        for _ in range(q):
            l, r = map(int, input().split())
            hull = st.query(l - 1, r - 1)
            print(len(hull))

if __name__ == "__main__":
    solve()
```线段树存储凸包，使得每个节点代表其区间的不可约结构。 在查询过程中，我们会重复合并外壳，并且每次合并操作都会强制执行与原始过程相同的删除条件，以确保一致性。 

最重要的实现细节是合并顺序。 左壳必须由右壳扩展，而不是相反，否则索引的单调性被破坏，凸性测试无效。 

## 工作示例

 ### 示例 1

 输入段：`[1, 5, 6, 8, 9]`我们将其处理为点`(i, a[i])`。 

| 步骤| 当前船体|
 | --- | --- |
 | 开始| (1,1) |
 | 加 (2,5) | (1,1),(2,5) |
 | 加 (3,6) | (1,1),(2,5),(3,6) |
 | 加 (4,8) | (1,1),(2,5),(3,6),(4,8) |
 | 添加 (5,9) | (1,1),(2,5),(3,6),(4,8),(5,9) |

 没有点违反凸条件，因此不会发生删除，答案为 5。 

这显示了一个完全凸的递增序列，其中没有任何内容可以被删除。 

### 示例 2

 输入段：`[1, 3, 2, 6, 4, 8]`| 步骤| 行动| 船体 |
 | --- | --- | --- |
 | 添加 1 | 初始化| (1,1) |
 | 添加 3 | 好的 | (1,1),(2,3) |
 | 添加 2 | 删除 3 条件 | (1,1),(3,2) | (1,1),(3,2) |
 | 添加 6 | 好的 | (1,1),(3,2),(4,6) | (1,1),(3,2),(4,6) |
 | 添加 4 | 删除 6 个条件 | (1,1),(3,2),(5,4) |
 | 添加 8 | 好的 | (1,1),(3,2),(5,4),(6,8) |

 最终船体尺寸为 4。 

这演示了当中间点违反凸性时如何删除它们，以及每次删除后删除如何级联。

 ## 边缘情况

 对于像这样的单元素段`[7]`，外壳的大小一般为 1，因为没有满足删除条件的内部点。 该算法初始化单点外壳并立即返回，因此不会调用合并逻辑。 

对于严格凸递增线段，例如`[1, 2, 3, 4, 5]`，每次添加都会保留凸性，因此在合并过程中不会删除任何点。 线段树节点也保留了完整的链，最终查询返回长度为5，符合任何内部位置都不能满足删除条件的事实。
