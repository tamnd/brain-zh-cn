 ## 解决方案
 ## 问题理解

 给定一个二进制字符串，我们想象将其分成几个连续的部分。 每个片段都被解释为使用通常从左到右的意义的二进制数，这意味着片段中最左边的字符贡献了 2 的最高幂。 

对于任何固定数量的片段，假设我们将字符串切成 k 段，每个段产生 k 个整数。 该分区的值是这 k 个整数的按位异或。 对于从 1 到 n 的每个可能的 k，我们需要两件事：分割成 k 段的所有方式可实现的最大 XOR 值，以及有多少个不同的分割达到该最大值（以固定常数为模）。 

最后，我们不是直接输出所有结果，而是将它们聚合成所有 k 上的四个基于 XOR 的摘要。 

因此，核心计算任务不仅仅是评估一种划分，而是理解当我们改变切割次数时最佳异或行为如何演变。 

字符串长度可能足够大，以至于无法枚举分区。 即使对于单个 k，分区的数量也是指数级的，因此除了非常小的输入之外，强力探索立即变得不可能。 任何可接受的解决方案都必须避免显式枚举分割，而是依赖于二进制子串的结构属性。 

一个关键的微妙之处是，当段移动一个位置时，子字符串值会严重重叠。 当扩展到 i+1 时，以位置 i 结尾的子串的值可以被重用，这表明端点或前缀关系上的动态编程比组合枚举更相关。 

当字符串均匀或极度倾斜时，就会出现边缘情况。 例如，如果字符串全为零，则无论 k 如何，每个分区都会产生异或零，因此所有最大值崩溃和计数都会变得组合很大。 如果字符串全为 1，则每个子字符串值仅取决于其长度，并且不同的分区可以以不明显的方式产生相同的 XOR 结果。 

当 k 等于 n 时，会出现另一种边缘情况，其中每个段都是单个字符。 在这种情况下，XOR 值固定为各个位的 XOR，因此别无选择，但计数仍然取决于普通分区的唯一性。 

## 方法

 一种简单的方法尝试直接评估每个分区的固定 k。 对于 n-1 个间隙中 k-1 个切割位置的每次选择，我们计算段值并对它们进行异或。 如果从头开始计算单个分区值，在最坏的情况下成本为 O(n)，并且总共有 O(2^n) 个分区。 即使限制为固定 k，我们仍然有 O(n 选择 k) 的可能性，即使对于中等 n 来说，这也太大了。 

稍微改进的版本使用前缀散列或 2 的前缀幂来预先计算所有子字符串的二进制值。 这将段值计算减少到 O(1)，但不能解决分区的组合爆炸问题。 主要成本仍然是割集的枚举。 

关键的观察是每个分区定义一组前缀端点，并且 XOR 操作与分割线性交互。 我们可以不考虑分段，而是考虑每个位位置如何对最终的 XOR 做出贡献，具体取决于它是被剪切还是与相邻位合并。 这将问题从组合分割转变为跟踪所有 k 中各个位置的贡献。 

一旦以这种方式重新表述，该结构就可以在前缀长度和段数上进行动态编程，其中转换仅取决于我们是扩展当前段还是开始一个新段。 二进制性质确保可以使用移位和 XOR 增量更新段值，从而避免重新计算。

这将问题简化为 n 个位置和 k 个段计数上的 DP，其中每个状态捕获可实现的最佳 XOR 以及实现它的方法数量。 转换是局部的，基于我们是否在位置 i 处放置剪切。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解分区 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | DP over 前缀和段计数 | O(n^2) 或优化 O(n log n) 取决于转换 | O(n^2) 或 O(n) | 已接受 |

 ## 算法演练

 我们从左到右处理字符串，同时维护一个 DP 表，其中 dp[i][k] 表示使用分成 k 段的前 i 个字符的最佳可能 XOR 值，以及实现它的方法数量。 

1. 将 dp[0][0] 初始化为具有 XOR 值 0 和计数 1 的中性状态，因为空前缀只有一个有效分解。 
2.对于从1到n的每个位置i，我们考虑所有可能小于i的先前切割位置j。 这定义了段 s[j+1:i]。 我们使用预先计算的前缀幂来计算其二进制值，这样我们就不会重新扫描子字符串。 
3. 对于从 dp[j][k-1] 开始的每个有效转换，我们通过将先前的 XOR 与 s[j+1:i] 的值相结合来计算候选 XOR。 我们将此候选与 dp[i][k] 进行比较。 
4. 如果候选 XOR 大于 dp[i][k] 的当前最佳值，我们将覆盖它并重置计数。 如果相等，我们将 dp[j][k-1] 中的路数相加。 
5. 我们对所有 i 和 k 重复此操作，直至 n，确保覆盖所有段计数。 
6. 填写表格后，dp[n][k] 给出每个 k 的答案。 然后我们计算所有 k 上所需的聚合 XOR 表达式 A、B、C、D。 

它之所以有效，是基于这样一个不变式：dp[i][k] 始终存储使用恰好 k 个覆盖直至 i 的前缀的连续段可实现的最佳 XOR。 每个有效分区必须在某个最后的剪切 j 处结束，并且转换精确地枚举最后的剪切。 由于 XOR 是关联的，并且段值一旦固定就是独立的，因此不会错过超出其计算值的段之间的交互。 DP 确保每个分区通过其最后一次切割分解准确地表示一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve(s):
    n = len(s)

    # prefix binary value: pref[i] = value of s[0:i]
    pref = [0] * (n + 1)
    for i, ch in enumerate(s, 1):
        pref[i] = (pref[i - 1] << 1) | (ch == '1')

    # dp[k][i] = (best_xor, count)
    dp = [[(-1, 0) for _ in range(n + 1)] for _ in range(n + 1)]
    dp[0][0] = (0, 1)

    def get_val(l, r):
        return pref[r] ^ (pref[l - 1] << (r - l + 1))

    for i in range(1, n + 1):
        for k in range(1, i + 1):
            best = -1
            cnt = 0
            for j in range(k - 1, i):
                prev_xor, ways = dp[k - 1][j]
                if ways == 0:
                    continue
                val = get_val(j + 1, i)
                cand = prev_xor ^ val
                if cand > best:
                    best = cand
                    cnt = ways
                elif cand == best:
                    cnt = (cnt + ways) % MOD
            dp[k][i] = (best, cnt)

    A = B = C = D = 0
    for k in range(1, n + 1):
        p, q = dp[k][n]
        p %= MOD
        q %= MOD
        A ^= p
        B ^= q
        C ^= (p * k)
        D ^= (q * k)

    print(A, B, C, D)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        s = input().strip()
        solve(s)
```前缀数组存储每个前缀的整数值，以便可以使用位移位和 XOR 在 O(1) 中重建任何子字符串值。 这避免了重复重新计算二进制转换。 

DP表通过段数和前缀长度来索引。 先前剪切位置上的内循环是关键的过渡，其中测试每个可能的最后一段。 该实现仔细确保只有有效状态 dp[k-1][j] 起作用。 

一个常见的陷阱是在计算二进制值时混淆子字符串索引。 移位量必须与精确的段长度匹配，否则不同的段将产生不一致的值。 另一个微妙的问题是忘记计数必须以 998244353 为模，而最后的 XOR 聚合不是模块化的。 

## 工作示例

 考虑一个短字符串`110`。 

当 k = 1 时，只有一个段：`110`计算结果为 6。对于 k = 2，我们可以将其拆分为`1 | 10`或者`11 | 0`。 对于 k = 3，仅存在单字符拆分。 

我们从概念上跟踪 dp[k][i]：

 | 我| k | 最后切 j | 段 | 异或到目前为止 | 最好的|
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 1 | 1 | 1 |
 | 2 | 1 | 0 | 11 | 11 3 | 3 |
 | 2 | 2 | 1 | 1 | 1 | 0 |
 | 3 | 2 | 1 | 1 | 10 | 10 2 |
 | 3 | 2 | 2 | 11 | 11 0 | 3 |

 该轨迹显示了不同的剪切位置如何产生竞争的 XOR 值，以及 dp 如何仅保留最大值。 

对于 k = 3，仅分区`1|1|0`存在，给出 XOR = 1 ^ 1 ^ 0 = 0。DP 反映了这种唯一性，因为只有一个有效的分解。 

这表明每个状态完全由最后切割分解确定，并且没有分区被错误地重复计算。

 ## 边缘情况

 对于像这样的全零字符串`000`，无论分段如何，每个子字符串的计算结果都为零。 DP 从未观察到任何大于零的候选异或，因此每个 dp[k][n] 稳定在零，而计数在所有有效切割结构上累积。 这证实了该算法正确处理退化值空间。 

对于完全交替的字符串，例如`1010`，子串值随边界变化很大。 DP 显式地评估每个剪切位置，因此即使局部段存在一位差异，XOR 转换也会正确传播这些差异。 这确保了不会遗漏段之间隐藏的依赖关系。
