 ## 解决方案
 ## 问题理解

 给定一个整数序列，并要求我们考虑它的所有非空子序列。 对于每个子序列，我们计算两个值：其中所有元素的最大公约数和其中所有元素的最小公倍数。 任务是计算有多少子序列具有这两个值相等的属性。 

解释此条件的一个有用方法是考虑一组数字具有相同的 gcd 和 lcm 意味着什么。 集合的 gcd 始终小于或等于集合中的每个元素，而 lcm 始终大于或等于集合中的每个元素。 为了使两者重合，每个元素必须完全相同，否则 lcm 将严格超过最小元素，或者 gcd 将低于最大元素。 这一观察结果将问题从在数论上看起来很重的问题转变为对等值的结构计数问题。 

输入只是一个整数数组，输出是此条件下有效子序列的数量。 

从约束的角度来看，关键的含义是我们是否能够负担得起迭代所有子序列的任何东西。 大小达到 10^5 左右的序列会立即排除任何指数探索。 如果在多个测试用例中重复，在最坏的情况下，即使对对进行二次计数也会变得太慢。 这促使我们寻求一种解决方案，将阵列压缩为频率计数并以线性或接近线性的时间工作。 

当尝试对 gcd 或 lcm 进行本地推理而不是全局推理时，会出现微妙的失败情况。 例如，在像这样的数组中`[2, 3, 4]`，一个天真的尝试可能会认为如果 gcd 和 lcm “碰巧相遇”，一些混合子序列可能会起作用，但检查显示：

 子序列`[2, 4]`gcd 2 和 lcm 4 不相等，并且`[2, 3, 4]`has gcd 1 and lcm 12. Only single-element subsequences work. 这强化了不同值的任何混合都会立即打破相等条件。 

Another edge case is when all elements are identical, for example`[5, 5, 5]`。 每个非空子序列都有效，所以答案应该是$2^3 - 1 = 7$。 任何忘记计算重数的解决方案都会错误地返回 1。 

## 方法

 暴力方法很容易描述。 我们迭代每个非空子序列，通过折叠其元素来计算其 gcd 和 lcm，并检查它们是否匹配。 这是正确的，因为它直接遵循问题的定义。 问题是子序列的数量：大小的数组$n$有$2^n - 1$子序列，甚至对于$n = 40$这已经变得不可行了，而$n = 10^5$使其完全不可能。 

关键的结构见解是 gcd 和 lcm 相等迫使子序列中的所有元素相同。 一旦认识到这一点，问题就不再依赖于 gcd 或 lcm 计算，而是减少到计算我们可以从每组相等值中选取非空子集的有多少种方法。 如果出现一个值$f$次，这些事件的任何子集形成一个有效的子序列，给出$2^f - 1$选择。 

我们将问题从枚举子序列简化为计算频率。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 频率计数 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取数组并计算每个不同数字出现的次数。 此步骤将序列压缩为具有相同值的等价类，这是可以形成有效子序列的唯一候选。 
2. 对于每个具有频率的不同值$f$，计算仅使用该值可以形成多少个非空子序列。 这是$2^f - 1$，因为除了空选项之外，每个出现的情况都可以包含或排除。 
3. 将所有不同值的这些贡献相加。 
4. 返回最终的总和作为答案。 

每个值独立求和背后的原因是，任何包含两个不同值的子序列都会立即违反条件，因此有效的子序列会按值干净地分区。 

### 为什么它有效

 仅当子序列的所有元素都相同时，它才满足 gcd 等于 lcm。 如果两个元素不同，则说$a < b$，那么 lcm 至少为$b$而 gcd 最多为$a$，所以平等是不可能的，除非$a = b$。 这迫使每个有效子序列完全包含在单个值类中。 该算法准确地枚举这些类，并对每个类中的所有非空子集进行计数，确保完整性且不会过度计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import Counter

def solve():
    n = int(input().strip())
    arr = list(map(int, input().split()))
    
    freq = Counter(arr)
    
    ans = 0
    for v, f in freq.items():
        ans += (1 << f) - 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```实现直接反映了推理。 频率表压缩数组，位移位`(1 << f)`有效地计算$2^f$。 减一会删除空子序列。 不需要 gcd 或 lcm 计算，因为结构参数完全消除了混合值子序列。 

一个微妙的实现细节是使用位移位而不是`pow(2, f)`，它避免了浮点开销，并且是整数求幂竞争编程的标准。

 ## 边缘情况

 当所有元素都相同时，例如`[10, 10, 10]`，该算法计算所有$2^3 - 1$子序列。 频率图生成频率为 3 的单个条目，并且计算正确地聚合了所有非空子集。 

当所有元素都不同时，例如`[1, 2, 3, 4]`，每个频率都是1，所以每个都有贡献$2^1 - 1 = 1$。 结果是 4，符合只有单元素子序列有效的事实。 

当存在主导值和许多稀有值时，例如`[5, 5, 5, 1, 2]`，该算法按值干净地分离贡献，确保不考虑无效的混合子序列。
