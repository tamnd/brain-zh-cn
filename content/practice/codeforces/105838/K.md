 ## 解决方案
 ## 问题理解

 我们得到一个写为十进制字符串的正整数。 在一次移动中，我们可以选择一对相邻的数字并交换它们。 我们最多可以执行一次此类交换，或者选择不执行任何操作。 目标是最大化此可选操作后的结果数。 

输入由多个独立的测试用例组成。 每个测试用例只是一个整数，我们必须输出通过零个或一个相邻交换可获得的最大可能整数。 

这些限制意味着所有测试用例的总位数很大，总计可达 200,000。 这立即排除了任何以嵌套方式在所有位置上独立尝试每个测试用例所有可能交换，然后重复重新计算完整比较的解决方案。 然而，由于每个测试用例都是独立的，并且操作计数与位数呈线性关系，因此每个数字的线性或近线性方法就足够了。 

当数字在字典意义上已经是最佳时，就会出现微妙的边缘情况，这意味着任何交换都会降低该值。 例如，像 987654 这样的非递增序列。任何交换都只会产生更小的数字，因此正确的答案是原始数字。 在局部改进不是全局最优的情况下，总是执行第一个改进局部更改的粗心贪婪交换可能会失败。 

另一个重要的边缘情况是出现相同的数字。 例如，1221。交换第一个相邻对会得到 2121，这比稍后交换或不执行任何操作要大。 该算法必须正确处理相等数字比较，而不将相等视为改进。 

最后，前导数字的考虑因素也很重要。 由于我们正在重新排列输入中不带前导零的正整数的数字，因此向前移动较大数字的任何交换都会显着改变幅度，因此比较必须按数字的字典顺序进行。 

## 方法

 蛮力的想法很简单：对于每个测试用例，尝试每个可能的位置 i，交换 i 和 i+1 处的数字，构造结果数字，并保留所有这些结果和原始数字中的最大值。 这是正确的，因为它详尽地探索了一步中可到达的所有允许状态。 然而，对于长度为 L 的数字，这需要 O(L) 次交换，并且每次交换花费 O(L) 来评估或重建字符串，在简单的实现中为每个测试用例提供 O(L^2) 。 在许多测试用例中，这变得太慢了。 

关键的观察是我们不需要尝试所有交换。 我们只关心尽早提高左侧的数字，因为较高的位置主导着值。 如果我们决定交换位置 i 和 i+1 处的数字，唯一重要的是提前放置较大的数字是否会产生比原始数字更好的前缀。 任何交换仅影响两个相邻位置，因此对数字的影响是局部的，我们可以在相对于原始结构的 O(1) 比较中模拟每次交换。 

因此，我们可以在每个测试用例中扫描一次所有相邻对，在本地模拟交换，并将结果字符串与迄今为止看到的最佳答案进行比较。 因为比较是按字典顺序进行的，并且只需要检查当前的最佳配置，所以我们可以增量地维护最佳配置，而无需重复重建不必要的状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每次测试 O(L^2) | O(L) | 太慢了|
 | 尝试所有相邻的交换一次 | 每次测试 O(L) | O(L) | 已接受 |

 ## 算法演练

 我们将每个数字视为可变的数字序列。

1. 将输入数字转换为字符列表，以便轻松模拟交换。 这允许恒定时间本地修改。 
2. 将答案初始化为原始数字，因为不执行任何操作始终有效。 
3. 从 0 到长度减 2 迭代每个索引 i。在每个位置，考虑交换 i 和 i+1 处的数字。 
4. 临时执行交换，形成候选配置。 
5. 使用数字字符串的字典顺序比较，将候选配置与当前最佳答案进行比较。 这种比较之所以有效，是因为两个字符串都表示相同长度的整数，并且没有引入前导零。 
6. 如果候选人更大，则更新最佳答案。 
7. 恢复交换，以便为下一次迭代保留原始序列。 
8.处理完所有相邻对后，输出最佳存储配置。 

仅相邻交换背后的关键原因是该问题将操作限制在这些交换上，因此搜索空间恰好是 L 个可能状态加上身份状态。 

### 为什么它有效

 每个有效结果要么是原始数字，要么是恰好交换一对相邻数字的结果。 该算法将所有此类可能性仅枚举一次。 由于最佳答案是在所有可达状态中选择的，并且比较是数字序列的精确字典顺序，因此不会跳过任何可以改进答案的候选答案。 因此，该算法是由操作约束定义的状态空间的完整枚举。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        s = list(input().strip())
        best = ''.join(s)

        n = len(s)
        for i in range(n - 1):
            s[i], s[i + 1] = s[i + 1], s[i]
            cand = ''.join(s)
            if cand > best:
                best = cand
            s[i], s[i + 1] = s[i + 1], s[i]

        out.append(best)

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案为每个测试用例维护一个可变列表，并避免从头开始重建所有状态。 每次交换都会在相对于数字移动的恒定时间内进行测试，并且字符串比较非常高效，因为 Python 按字典顺序进行比较并在不匹配时提前停止。 交换-恢复模式可确保正确性，而无需每次迭代分配额外的数组。 

一个常见的实现陷阱是忘记恢复交换，这将导致后续迭代在损坏的状态上运行。 另一个是在嵌套循环内不必要地重建字符串，这将使运行时更接近二次行为。

 ## 边缘情况

 对于像这样的个位数`7`，没有相邻的对可以交换。 该算法将最佳答案初始化为原始字符串，并且永远不会进入循环，因此它会正确输出`7`。 

对于像这样的递减序列`543210`，每次交换都会产生一个按字典顺序更小的字符串。 该算法仍然评估所有相邻的交换，但从不更新最佳值，保持原始值不变。 

对于重复的数字，例如`11111`，每次交换都会产生相同的字符串。 比较`cand > best`从不触发，因此输出保持不变，正确地避免了不必要的更新。
