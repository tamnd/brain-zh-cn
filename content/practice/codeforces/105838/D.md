 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 每个测试用例中都有$n$洞穴标记为 1 到$n$，以及一系列$n$计划检查，每次检查针对一个洞穴。 该顺序是固定的并且是预先已知的。 

玩家必须准确选择一个洞穴$x$躲进去，事后无法改变。 目标是选择一个在整个序列中从未被检查过的洞穴。 换句话说，我们想要一个值$x$介于 1 和$n$使其不会出现在数组中的任何位置。 

每个测试用例的输出是任何此类有效的洞穴编号（如果存在），否则当每个洞穴从 1 到$n$至少出现一次。 

约束允许最多 1000 个测试用例，总计$n$在所有测试中直至$2 \cdot 10^5$。 这意味着每个测试用例大致呈线性的任何解决方案都可以，但是每个测试用例的任何二次方都会太慢，因为它可能会退化到大约$10^{10}$最差分布中的操作。 

当数组是以下元素的排列时，会出现一种微妙的情况$1..n$。 在这种情况下，每个数字都只出现一次，因此没有有效的选择，答案必须是 -1。 另一个边缘情况是$n = 1$。 如果唯一值为1，则答案为-1； 如果不知何故它不是 1（由于约束而不可能发生），它将是 1。 

一个天真的错误是假设答案始终是最小的缺失数字，而没有正确跟踪存在，或者忘记我们必须考虑整个范围$1..n$，而不仅仅是序列中出现的值。 

## 方法

 最直接的想法就是尝试每一个候选洞穴$x$从 1 到$n$，并对每一个扫描整个序列以检查它是否出现。 如果我们发现任何$x$永远不会出现的，我们立即输出它。 

这是有效的，因为它明确地验证了问题中的条件。 然而，成本很高。 对于每个$n$候选人，我们最多可以扫描$n$元素，导致$O(n^2)$每个测试用例。 总共有$2 \cdot 10^5$，这变得太慢了。 

关键的观察是我们不需要独立测试每个候选人。 我们只关心哪些值至少出现一次。 一旦我们知道了当前值的集合，从 1 到任何数字$n$不在该集合中是有效的。 这将问题减少到单遍标记结构。 

我们可以维护一个大小的布尔数组$n$，标记每个看到的值，然后扫描一次以查找任何未标记的索引。 这使得解决方案的每个测试用例的时间都是线性的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了|
 | 标记/布尔数组|$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 对于每个测试用例，请阅读$n$和数组$a$。 我们想要记录从 1 到$n$出现。 
2. 创建布尔数组`seen`尺寸的$n+1$，初始化为 false。 这将跟踪每个洞穴编号是否出现在检查序列中。 
3.遍历数组$a$。 对于每个值$a_i$， 标记`seen[a_i] = true`。 此步骤将有关序列的所有信息压缩为存在数据。 
4.处理完所有元素后，从1迭代到$n$。 第一个索引$x$这样`seen[x]`为 false 是有效答案，因为它从未出现在序列中。 
5.如果没有这样的$x$存在，输出-1。 当从 1 到每个数字时，就会发生这种情况$n$被标记，意味着该序列包含所有可能的洞穴。 

为什么它有效：该算法将问题简化为检查集合中的成员资格。 由于唯一的要求是序列中不存在，因此任何未标记为存在的值都自动有效。 如果所有值都被标记，则序列覆盖整个域，不留下有效的选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []
    for _ in range(T):
        n = int(input())
        a = list(map(int, input().split()))
        
        seen = [False] * (n + 1)
        for x in a:
            seen[x] = True
        
        ans = -1
        for i in range(1, n + 1):
            if not seen[i]:
                ans = i
                break
        
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```实施直接遵循标记策略。 这`seen`每个测试用例都会重置数组，确保用例之间不会泄漏。 第一个循环将输入压缩为存在信息。 第二个循环执行线性扫描以查找任何缺失值。 

一个微妙的细节是，我们在第一个缺失值处停止，而不是收集所有缺失值，因为任何有效答案都是可以接受的。 这可以使逻辑最小化并避免不必要的工作。

 ## 边缘情况

 一个关键的边缘情况是当数组是以下元素的完美排列时$1..n$。 例如：```
1
4
1 2 3 4
```对于所有索引 1 到 4，标记数组都完全为真。扫描未发现错误条目，并且算法正确输出 -1。 

另一种情况是序列仅包含一个重复值：```
1
5
2 2 2 2 2
```这里只有索引 2 被标记为 true。 扫描立即找到 1 作为第一个缺失值并返回它。 这表明重复项不会影响正确性，因为我们只关心存在性，而不关心频率。
