 ## 解决方案
 ## 问题理解

 在第一个洗涤阶段之后，每种袜子颜色恰好出现两次，但是相同颜色的两只袜子可能位于不同的对中。 我们可以将每个原始对视为两种颜色之间的连接。 一对包含颜色`a`和`b`成为顶点之间的边`a`和`b`在图表中。 

因为每种颜色恰好出现在两只袜子中，所以每个顶点的度数恰好为 2。 因此，该图由独立的循环组成。 一双颜色相同的袜子是一种特例：它是一个长度为1的循环，用自循环表示。 

仅当该集合中的每种颜色出现偶数次时，魔盆才会接受该集合中的对。 用图术语来说，所选边必须为每个顶点赋予偶数度数。 这样的集合是欧拉子图。 

任务是找到盆地的最小可能容量，其中容量表示单次魔法操作中使用的最大原始对数量。 

对数可达$10^5$。 尝试许多可能的子集或模拟任意分组的算法很快就会变得不可能，因为可能的边缘选择的数量呈指数增长。 即使是重复扫描整个图以查找每个可能分组的算法也将过于昂贵。 必须使用图的结构，以便每对仅被处理恒定的次数。 

棘手的部分是认识到循环不能被分成更小的有效组。 例如，具有三个边的循环：```
1 2
2 3
3 1
```有答案`3`。 尝试仅使用其中两个边缘会使其中一种颜色的计数为奇数，因此盆会失败。 

另一个边缘情况是自循环。 输入```
1
1
1 1
```有答案`1`。 粗心的图实现可能会忽略自循环，因为它们不连接两个不同的顶点，但一对相同的颜色本身已经形成了一个有效的组。 

另一种情况是多个周期独立存在。 例如：```
1
4
1 2
2 1
3 4
4 3
```有答案`2`。 两个平行边循环均可单独处理。 将整个图视为一个周期将错误地返回`4`。 

## 方法

 直接的暴力方法会尝试找到颜色都出现偶数次的颜色对组。 它可以生成可能的边缘子集，检查每种颜色是否出现偶数次，然后搜索最小化最大子集大小的分区。 这是正确的，因为它检查了使用盆的所有可能的方式。 然而，即使检查所有子集也已经需要$2^n$的可能性。 和$n=10^5$，这远远超出了任何实现可以处理的范围。 

有用的观察来自于图形表示。 由于每个顶点都有二度，因此每个连通分量都是一个循环。 循环有一个特殊的属性：由其边缘组成的唯一非空欧拉子图是整个循环本身。 如果我们从循环中删除偶数一条边，则删除的边的两个端点将成为路径的端点，并且这些顶点在所选边内具有奇数度。 

这意味着每个周期必须作为一个整体放入一个魔法操作中。 尝试组合循环没有任何好处，因为组合两个循环只会增加该操作所需的容量。 因此，最小可能容量是图中最大循环的大小。 

最佳解决方案就是找到所有连接的组件并记录任何组件中最大数量的边。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 根据袜子对构建图表。 每种颜色都是一个顶点，每一对贡献一条边。 自循环被存储为普通边，因为相同颜色的对已经是一个完整的循环。 
2. 使用深度优先搜索遍历每个未访问的颜色。 在遍历过程中，计算有多少条边属于该连接的组件。 由于该图仅由循环组成，因此该计数正是必须放置在一起的对的数量。 
3. 保留所有遍历过程中找到的最大组件边数。 该值是可能的最小流域容量。 
4. 输出最大元件尺寸。 

为什么它有效：

 每个连通分量都是一个环，因为每个顶点都有二度。 循环不能分成更小的有效魔法操作，因为删除任何边都会创建具有奇数度数的顶点。 因此，每个组件都会贡献一个不可避免的下限，该下限等于其边数。 单独处理每个组件可以实现该限制，因此最大的组件大小既是必要的也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        graph = {}

        for _ in range(n):
            a, b = map(int, input().split())
            if a not in graph:
                graph[a] = []
            if b not in graph:
                graph[b] = []
            graph[a].append(b)
            graph[b].append(a)

        visited = set()
        best = 0

        for start in graph:
            if start in visited:
                continue

            stack = [start]
            visited.add(start)
            vertices = 0

            while stack:
                u = stack.pop()
                vertices += 1
                for v in graph[u]:
                    if v not in visited:
                        visited.add(v)
                        stack.append(v)

            best = max(best, vertices)

        ans.append(str(best))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```该图被存储为邻接列表。 添加边时，会在两个方向上添加，包括自循环情况。 对于自循环，同一个顶点接收两个条目，这正是它的度贡献。 

深度优先搜索对连通分量中的顶点进行计数。 在这个图族中，每个组件都是一个循环，因此顶点数等于边数。 这也可以正确处理自循环组件，因为它包含一个顶点和一条边。 

当顶点被压入堆栈时，遍历会立即标记顶点。 这避免了多次访问同一周期并保持总工作线性。

 | 测量| 复杂性 | 说明|

 ## 边缘情况

 对于单个自循环：```
1
1
7 7
```该图有一个顶点和一个自环。 邻接表包含两个对顶点的引用`7`，遍历找到组件中的一个顶点。 由于自环代表一对，因此组件大小为`1`，所以答案是`1`。 

对于看起来可拆分的循环：```
1
3
1 2
2 3
3 1
```贪婪的方法可能会尝试先获取两对，但这两条边会留下一种颜色出现一次。 遍历看到一个包含所有三个顶点的连通分量，给出所需的答案`3`。 

对于多个断开连接的组件：```
1
4
1 2
2 1
3 4
4 3
```第一个组件包含颜色`1`和`2`，第二个包含颜色`3`和`4`。 每个组件都可以独立处理能力`2`。 该算法从不合并它们，因此它不会高估答案`4`。
