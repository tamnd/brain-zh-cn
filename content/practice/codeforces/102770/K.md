 ## 解决方案
 ## 问题理解

 该问题描述了解决同一图形任务的两种算法。 对于每种可能的输入大小`n`，我们知道预期算法的运行时间和较慢的暴力算法的运行时间。 竞赛时间限制选择为 Chenjb 减少最大输入大小后剩余的最大测试用例上预期算法运行时间的三倍。 

对于选定的最大尺寸`n`，测试数据可以包含以下每个尺寸`1`到`n`。 由于预期的解决方案变得更慢`n`增长，这些测试中最慢的预期运行是具有大小的测试`n`本身。 该选择的时间限制是`3 * a[n]`。 如果存在任何尺寸最大的测试用例，则暴力解决方案在该输入尺寸下会失败`n`其运行时间大于此限制。 

输入最多提供 50 种可能的尺寸。 两个运行时间数组都已按非降序排序。 小限制意味着即使直接扫描所有尺寸也足够了。 不需要高级数据结构或对数搜索。 重要的观察是，答案是关于暴力算法变得太慢的测试用例的最早前缀，而不是仅比较相同的索引。 

一个常见的错误实现检查是否`b[n] > 3 * a[n]`并停在那里。 这会错过较小的测试用例已经突破限制的情况。 例如：```
1
4
1 2 7 20
2 5 30 40
```正确的输出是`3`。 为了`n = 3`，时间限制为`21`。 大小的暴力破解时间`3`是`30`，所以失败了。 比较于`n = 4`不需要，因为我们想要尽可能小的值。 

另一种极端情况是暴力算法总是适用。 例如：```
1
3
2 3 3
5 7 8
```输出是`-1`。 最大预计时间是`3`，所以时间限制是`9`。 每次暴力破解时间最多为`9`，这意味着没有允许的输入大小会导致失败。 

最终的边缘情况是单一可能的大小：```
1
1
10
31
```输出是`2`？ 此输入无效，因为`m = 1`，所以唯一有效的输出是`1`或者`-1`。 正确的推理是时间限制是`30`，暴力破解时间为`31`，所以输出是：```
1
```仅从第二个元素开始检查的解决方案将错误地错过此边界情况。 

## 方法

 一种直接的方法是模拟 Chenjb 的决策过程。 对于每个可能的最大输入大小`n`，将时间限制计算为`3 * a[n]`。 然后从大小检查每个测试用例`1`到`n`看看暴力破解时间是否超过这个限制。 这完全遵循传递的定义。 

暴力法是正确的，因为它直接检查暴力解通过所需的每个条件。 然而，它重复了许多比较。 和`m`大小，分别检查每个前缀最多执行`1 + 2 + ... + m`比较，即`O(m^2)`。 最大`m`只有 50，所以这已经足够快了。 

更好的观察是暴力破解时间是排序的。 对于固定的最大尺寸`n`，所有测试用例中最长的暴力运行时间`1`到`n`简直就是`b[n]`。 最大预期运行时间也是`a[n]`。 这消除了扫描前缀的需要。 

条件变为：```
b[n] > 3 * a[n]
```第一个满足这个条件的索引恰好是暴力解无法通过的第一个输入大小。 我们可以扫描数组一次，并在满足条件时立即停止。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(平方米) | O(1) | O(1) | 已接受 |
 | 最佳 | O(米) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取所有尺寸的预期求解时间和强力求解时间`1`到`m`。 

数组已经排序，因此位置处的值`i`描述了前缀中最慢的情况`i`。 
2. 对于每个尺寸`i`从`1`到`m`，计算时间限制为`3 * a[i]`。 

如果 Chenjb 允许输入大小为`i`，最大的测试用例有大小`i`，所以它的预期运行时间决定了时间限制。 
3. 检查是否`b[i]`大于这个时间限制。 

由于暴力破解时间不会减少，`b[i]`是所有大小中最糟糕的暴力情况`i`。 如果超过限制，则暴力解决方案在该前缀上失败。 
4. 打印条件为真的第一个索引。 

扫描从小尺寸到较大尺寸，因此第一次失败是最小可能的答案。 
5. 如果扫描完成后没有找到这样的索引，则打印`-1`。 

这意味着暴力解决方案可以处理每个允许的输入大小。 

为什么它有效：

 对于任何选定的最大尺寸`i`，竞赛包含的测试用例的大小最多为`i`。 其中预期的解决方案运行最慢的是`a[i]`，给出极限`3 * a[i]`。 其中，蛮力解决方案运行最慢的是`b[i]`因为数组是有序的。 蛮力解决方案恰好在以下时间通过：`b[i] <= 3 * a[i]`。 该算法会检查每个可能的确切条件`i`按升序排列，因此它找到的第一个失败是最小的有效答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        m = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        res = -1
        for i in range(m):
            if b[i] > 3 * a[i]:
                res = i + 1
                break

        ans.append(str(res))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```输入一次处理一个测试用例。 数组在 Python 中使用从零开始的索引，而问题的大小从`1`，所以答案是`i + 1`当发现故障时。 

该循环将每个大小的暴力破解时间与相同大小的预期时间的三倍进行比较。 不需要前缀扫描，因为两个数组都已排序，因此当前位置已经代表了前缀中最坏的情况。 

乘以`3`是安全的，因为最大值非常小。 早期的`break`避免在发现第一个失败尺寸后进行不必要的检查。

 ## 边缘情况

 第一个边缘情况是最小尺寸的失败。 为了：```
1
1
10
31
```时间限制是`30`，而暴力破解时间是`31`。 循环检查索引`0`立即，看到`31 > 30`，并返回`1`。 它并不假设在失败之前必须达到更大的尺寸。 

第二种边缘情况是一种永远不会超出限制的强力解决方案：```
1
3
2 3 3
5 7 8
```限制是`6`,`9`， 和`9`。 每个蛮力时间都适合，因此循环永远不会更新答案并打印`-1`。 

第三种边缘情况是由当前大小而不是以后的大小引起的失败：```
1
4
1 2 7 20
2 5 30 40
```按尺寸`3`，极限为`21`暴力破解时间是`30`。 算法返回`3`立即地。 继续使用更大的尺寸只能给出更大的候选尺寸，这不是所要求的最小值。
