 ## 解决方案
 ## 问题理解

 我们需要计算给定的包含间隔内有多少个日历日具有其属性`YYYYMMDD`表示包含三个连续数字`202`。 

日期不作为数字与属性进行比较。 实际的八个字符表示很重要。 例如，`22020101`包含`202`因为子字符串从年份的第二位数字开始，而`20190202`包含它是因为子字符串从年份跨越到月份。 

输入最多包含`10^5`独立的日期间隔。 年份仅限于`2000`通过`9999`，所以只有 8000 年可能。 这排除了每天扫描每个查询的情况，因为整个范围包含近三百万天，并且这样做的时间`10^5`案件将接近`3 * 10^11`日期检查。 小的固定年份范围建议对所有年份进行一次预处理并使用前缀和回答每个查询。 

棘手的部分是边界和不同的地方`202`可以出现。 粗心的解决方案可能只会检查年份是否包含`202`以及漏掉涉及月份和日期的情况。 例如，间隔`2111 02 01`到`2111 02 03`只有一个有效日期，`21110202`，因为子字符串是由月份和日期部分组成的。 另一个错误是排除结束日期。 为了`2020 01 01`到`2020 01 02`，两个日期都是有效的，因为两个完整字符串都包含`202`，所以答案是`2`。 

闰年也很重要。 例如，间隔`2200 02 28`到`2200 03 01`包含两天，而不是三天，因为 2200 年不是闰年。 

## 方法

 直接的解决方案是迭代间隔中的每个日期，将其转换为`YYYYMMDD`，并检查是否`"202"`出现。 这很容易证明是正确的，因为每天都会被检查一次。 然而，最大可能的时间间隔是从 2000 年到 9999 年，大约包含 290 万天。 重复这项工作`10^5`查询远远超出了限制。 

关键的观察结果是，与查询数量相比，日历范围很小。 可能的年数只有 8000 年。 我们可以通过计算每年包含多少个有效日期来进行预处理`202`，并且还在年份内存储前缀信息。 

对于查询，答案变为：`number of valid days in years before Y2`加`number of valid days from January 1 to the ending date`，减去为开始日期前一天计算的相同值。 

这会将每个查询在预处理后变成恒定量的工作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每个查询的 O（范围内的天数）| O(1) | O(1) | 太慢了|
 | 最佳| O(8000 * 366) 预处理后每个查询的 O(1) | O(8000 * 13 * 32) | 已接受 |

 ## 算法演练

 1. 预先计算从2000年到9999年的每一年的信息。对于每一年，模拟所有有效的月份和日期，创建八位日期字符串，并统计其是否包含`202`。 

年数是固定的且很小，因此这种预处理成本低廉，并且消除了查询中的重复工作。 
2. 存储一个前缀数组，其中`prefix[y]`是从 2000 年到年底的有效日期数`y`。 

这允许立即回答查询边界之前的整年。 
3. 对于每年，还按月和日存储累积计数。 当查询在该年年中结束时，这让我们只计算该年的年初。 
4. 定义一个函数，返回有效日期的数量`2000-01-01`到任何给定日期。 

它将预先计算的完整年份与部分年份信息结合起来。 
5. 回答每个查询：`count(end_date) - count(day_before_start_date)`减去前一天可以正确处理包含间隔。 

为什么它有效：

 前缀函数始终精确计算从固定起点到请求日期的天数。 对于查询间隔，删除第一天之前的所有内容都会留下间隔内的天数。 由于每个日期都是按照其完整日期来计算的`YYYYMMDD`预处理期间的表示，不可能发生`202`被错过了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def leap(y):
    return y % 400 == 0 or (y % 4 == 0 and y % 100 != 0)

days_in_month = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]

year_pref = [0] * 10001
inside = {}

for y in range(2000, 10000):
    cur = [[0] * 32 for _ in range(13)]
    total = 0
    for m in range(1, 13):
        limit = days_in_month[m - 1]
        if m == 2 and leap(y):
            limit += 1
        for d in range(1, limit + 1):
            if "202" in f"{y:04d}{m:02d}{d:02d}":
                total += 1
            cur[m][d] = total
    inside[y] = cur
    year_pref[y] = year_pref[y - 1] + total

def count_to(y, m, d):
    if y < 2000:
        return 0
    ans = year_pref[y - 1]
    if m:
        ans += inside[y][m][d]
    return ans

def previous_day(y, m, d):
    d -= 1
    if d == 0:
        m -= 1
        if m == 0:
            return y - 1, 12, 31
        d = days_in_month[m - 1]
        if m == 2 and leap(y):
            d += 1
    return y, m, d

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        y1, m1, d1, y2, m2, d2 = map(int, input().split())
        py, pm, pd = previous_day(y1, m1, d1)
        out.append(str(count_to(y2, m2, d2) - count_to(py, pm, pd)))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```预处理循环构建两种信息。`year_pref`商店竣工数年，同时`inside[y]`存储某一特定年份内的累积答案。 后者避免了在每次查询期间迭代数月和数天。 

查询函数首先获取目标年份之前的所有完整年份，然后添加目标年份内的部分计数。 使用前日函数是因为前缀函数包含在内。 如果没有它，开始日期将被计算两次。 

Python 整数在这里不会溢出，因为整个支持范围内的总天数只有几百万。 要避免的主要实施细节是在跨月边界向后移动时正确处理二月。

 ## 边缘情况

 子字符串可以跨越年份边界进入月份或日期。 对于输入`2111 02 01 2111 02 03`，该算法不仅仅检查年份。 在预处理过程中，它检查完整的字符串`21110202`，所以答案是正确的`1`。 

一年包含`202`使该年的每一天都有效。 为了`2202 01 01 2202 12 31`，子字符串出现在年份数字本身中。 2202年的预处理值为该年的天数，即`365`，查询返回完整年份计数。 

闰年影响可以存在的日期数量。 为了`2200 02 28 2200 03 01`，向后的日期计算使用公历规则并认识到 2200 年不是闰年。 2 月有 28 天，因此不会引入无效的 2 月 29 日。
