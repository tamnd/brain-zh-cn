 ## 解决方案
 ## 问题理解

 林克使用滑翔伞在湖上移动。 水平移动的唯一方法是在滑翔伞打开时，最快的水平移动是高速直线移动`vh`。 飞行时，由于滑翔伞高速下降，他的高度会降低`vp`，除非他位于风洞正上方，且风洞的风力大于`vp`。 这样的山洞让他长高了。 

输入给出了起点和目的地坐标、三个速度以及所有洞穴的位置和风力强度。 目标是找到在不低于零高度的情况下到达目的地点所需的最短时间。 

有趣的是，高度看起来应该是一个额外的状态变量，这将使问题变得连续且困难。 这些限制表明这不是有意的。 一个案例最多有 4000 个洞穴，所有案例的洞穴总数为 10000 个。`O(n^2)`解决方案是可以接受的，因为它对最大的单个案例执行大约 1600 万次操作。 任何明确尝试每条路线的解决方案都是不可能的，因为可能的路线数量呈指数级增长。 

主要的边缘情况来自于对哪些洞穴重要的误解。 风速不大于的洞穴`vp`无法增加高度，因此将其用作充电点是没有用的。 洞穴仍然可能是距离目的地最近的点，但在那里停留并没有什么帮助，因为在离开之前必须恢复到达洞穴所花费的高度。 另一个常见的错误是忘记起始洞穴可以产生无限的高度，但所有其他有用的洞穴只有在到达它后才重要。 

例如，如果输入是：```
0 0 10 0
5 4 2
1
0 0 5
5 0 1
```第二个洞穴有风速`1`，比滑翔伞下落速度弱`4`。 它不能用作充电点。 将每个洞穴视为可免费充电的图节点的解决方案会低估答案。 

第二个例子是：```
0 0 3 4
5 4 1
0
0 0 5
```答案是`25`。 直接距离是`5`，水平移动需要`5 / 1 = 5`秒。 起始洞穴高速上升`1`，所以链接需要`20`几秒钟即可为行程创造足够的高度。 

## 方法

 第一个想法是将每个洞穴建模为图节点并尝试每条可能的路线。 对于每次过渡，我们都会跟踪前往下一个洞穴所需的高度并模拟攀爬时间。 这是正确的，因为穿过洞穴的路线完全决定了移动计划。 然而，直接探索路线是不可能的。 即使只有 4000 个洞穴，可能的序列数量也是巨大的。 

关键的观察结果是高度不需要存储为状态的一部分。 考虑到达一个高度为零的有用洞穴。 从那时起，洞穴就可以创造出任何所需的高度。 为一段长度的飞行创造足够的高度所需的时间`d`仅由当前洞穴决定。 

有风速的洞穴`v`大于`vp`以速度增加高度`v - vp`。 飞行距离`d`需要`d / vh`秒和消耗`vp * d / vh`高度。 因此，充电时间为：```
(vp * d / vh) / (v - vp)
```添加实际飞行时间得出：```
d / vh * v / (v - vp)
```这意味着每个有用的洞穴都有固定的成本才能到达另一个有用的洞穴。 该问题变成了有用洞穴上的最短路径问题，目的地作为只能进入的最终节点。 

暴力破解之所以有效，是因为每条有效路线都被表示出来，但当路线数量激增时，暴力破解就会失败。 观察到唯一必要的状态是当前有用的洞穴，这让我们可以将问题简化为 Dijkstra 算法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最佳| O(n²) | O(n) | 已接受 |

 ## 算法演练

 1. 只保留风速大于的洞穴`vp`。 这些是唯一可以增加高度的洞穴。 起始洞穴始终包含在内，因为该声明保证其风力足够强。 
2. 从起始洞穴开始运行 Dijkstra 算法。 洞穴的距离代表在零高度下到达该洞穴所需的最短时间。 
3. 加工洞穴时`i`，尝试移动到其他有用的洞穴`j`。 设它们的水平距离为`d`。 过渡成本为：```
d / vh * vi / (vi - vp)
```因为洞穴`i`首先必须提供足够的飞行高度。 

1.也可以考虑从当前洞穴直接飞行到目的地。 由于目的地没有风洞，因此适用相同的公式。 
2. 到达目的地所得到的最小值就是答案。 

为什么它有效：最短路径计算的不变性是每个存储的洞穴距离对应于以零高度到达那里。 这已经足够了，因为正风洞可以在之后重建任意高度。 任何最佳旅程都可以分为有用洞穴之间的航班，并且每个航班都具有图表所使用的转换成本。 由于所有边权重均为正，Dijkstra 找到了可能的最小总时间。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

def solve():
    t = int(input())
    ans_out = []

    for _ in range(t):
        sx, sy, tx, ty = map(int, input().split())
        vf, vp, vh = map(int, input().split())
        n = int(input())

        caves = []
        for _ in range(n + 1):
            x, y, v = map(int, input().split())
            if v > vp:
                caves.append((x, y, v))

        m = len(caves)
        dist = [float("inf")] * m
        used = [False] * m

        start = 0
        for i, (x, y, v) in enumerate(caves):
            if x == sx and y == sy:
                start = i
                break

        dist[start] = 0.0
        answer = float("inf")

        for _ in range(m):
            u = -1
            best = float("inf")
            for i in range(m):
                if not used[i] and dist[i] < best:
                    best = dist[i]
                    u = i

            if u == -1:
                break

            used[u] = True
            x, y, v = caves[u]

            direct = math.hypot(x - tx, y - ty)
            answer = min(answer, dist[u] + direct / vh * v / (v - vp))

            factor = v / (v - vp) / vh
            for j in range(m):
                if not used[j]:
                    nx, ny, _ = caves[j]
                    d = math.hypot(x - nx, y - ny)
                    nd = dist[u] + d * factor
                    if nd < dist[j]:
                        dist[j] = nd

        ans_out.append("{:.15f}".format(answer))

    print("\n".join(ans_out))

if __name__ == "__main__":
    solve()
```输入循环立即删除不可用的洞穴。 这是安全的，因为洞穴里有`v <= vp`从不提供正高度，因此他们无法改进任何路线。 

Dijkstra 数组只存储有用的洞穴。 转换公式使用浮点值，因为所需的精度为`1e-9`。 Python整数是任意精度的，因此在坐标计算中不存在溢出风险，并且`math.hypot`避免手动计算平方根。 

目标不作为普通图形节点插入。 相反，每当某个洞穴从优先顺序中删除时，我们就会测试从该洞穴到目的地的直飞航班。 这可以避免创建不必要的边缘。

 ## 边缘情况

 风速恰好等于滑翔伞下落速度的洞穴没有净垂直运动。 该算法将其删除，因为它无法创建高度。 例如，如果一个洞穴有`v = vp`，在那里等待永远不会改变高度，因此将其视为补给位置会产生不正确的捷径。 

目的地附近的弱洞穴看起来很有吸引力，因为最终的水平距离很小。 该算法通过证明这样的洞穴没有帮助来避免这个错误。 达到它会消耗其他地方产生的高度，并且它无法替代该高度。 最好的策略总是从先前有用的洞穴直接飞行。 

起始洞很特别，因为它保证有正风。 该算法从时间为零的那个洞穴开始，不需要单独的攀爬初始化步骤，因为过渡公式已经包括生成高度所需的时间。
