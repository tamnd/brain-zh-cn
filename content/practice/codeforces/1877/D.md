 ## 解决方案
 ## 问题理解

 我们得到一个索引从 1 到 n 的数组。 我们反复选择索引的非空子集并将它们标记为特殊。 这些选定的指数为黑色。 此后，任何仍未选择的索引如果是至少一个黑色索引的倍数，则将变为绿色。 其他一切都保持白色。 

选择的分数在此传播步骤之后定义：我们查看所有黑色或已变为绿色的索引，并取其中的最大数组值。 我们必须计算每个非空索引子集的分数，并将所有这些分数相加。 

困难来自于这样的事实：每个选择的子集都会影响可分性的确定性闭包，并且该闭包在很大程度上取决于数论结构而不是局部邻接性。 

约束允许 n 最大为 100000，值最大为 100000。直接枚举所有子集是不可能的，因为有 2^n 个子集。 即使存储每个子集状态也是不可行的。 这立即排除了任何显式模拟子集或执行每个子集传播的解决方案。 

一种简单的方法可能会尝试为每个子集标记所有倍数并计算最大值。 即使传播速度很快，迭代所有子集也已经使这个指数增长。 该问题需要重新表述，其中元素的贡献是组合计算的，而不是枚举的。 

当大索引通过整除性支配小索引时，就会出现微妙的边缘情况。 例如，如果我们选择索引 1，它总是激活所有索引，因此无论其他选择如何，分数只是全局最大值。 如果幼稚的实现独立于绿色闭包来处理黑色元素，则可能会低估这种主导地位。 

另一种边缘情况是仅选择大索引时。 例如，仅选择索引 n 不会激活数组的大部分，除非许多索引整除 n。 这使得传播不对称并且依赖于除数结构。 

## 方法

 暴力解决方案枚举索引的每个非空子集。 对于每个子集，我们计算闭包：将所选索引标记为黑色，然后将所选索引的所有倍数标记为绿色，最后扫描所有激活的索引以找到最大值。 这是正确的，因为它直接遵循所描述的过程。 然而，即使对于 n = 20，也有超过一百万个子集，而对于 n = 100000，这变得完全不可行。 每次评估的成本高达 O(n)，因此总复杂度为 O(n · 2^n)，这远远超出了任何限制。 

关键的观察是我们不需要跟踪子集。 相反，我们扭转观点：固定一个值阈值，并询问有多少个子集的最大激活值至少是该阈值。 这自然会导致按值对索引进行排序并按降序处理它们。 一旦我们考虑索引 i，所有较高的值都已被考虑在内，我们只需要计算使 i 成为第一个激活最大值的子集。 

传播规则仅取决于整除性，因此每个索引 i 可以被视为激活所有倍数的“生成器”。 因此，子集是否贡献 i 作为最大值取决于它是否包含至少一个强制 i 或其除数激活的索引。 该结构与索引相乘，我们可以使用除数的包含-排除来计算有效子集。

我们按 a[i] 的降序处理索引。 当考虑 i 时，我们通过确保没有更高值的索引被激活来计算 i 是最大激活元素的子集。 这减少了对子集的计数，避免“阻止”更高的贡献，同时仍然通过其除数结构激活 i。 可以使用预先计算的除数列表和对独立分量的乘法子集计数来完成结果计算。

 ## 算法演练

 1. 按 a[i] 的值递减对索引进行排序。 我们首先处理较大的值，以便在处理索引时，所有严格较大的值都已在最终贡献逻辑中得到考虑。 这确保了我们始终在当前值最大的情况下计算贡献。 
2. 预先计算直到 n 的每个索引的所有除数。 这是必要的，因为绿色传播完全取决于整除性，因此每个激活路径都是由除数关系而不是邻接决定的。 
3. 维持一个跟踪哪些指数已经“被较高值激活”的结构。 我们在概念上标记索引，如果给定索引包含在子集中，则这些索引将阻止给定索引成为最大值。 
4. 对于按 a[i] 降序排列的每个索引 i，计算 i 成为最大激活值的子集的数量。 这需要对包含至少一种激活 i 的配置的子集进行计数，但排除具有可能支配 i 的严格较大值的所有索引。 
5. 为了计算有效子集，我们将问题分解为 i 的约数。 每个除数独立地影响 i 是否通过黑到多传播规则可达。 我们对这些除数分量使用组合计数。 
6. 将 a[i] 乘以 i 的有效子集数量添加到最终答案中。 这将所有指数的贡献汇总为所有子集的潜在最大值。 
7. 继续，直到处理完所有索引，确保每个子集在其最大激活元素下精确计数一次。 

### 为什么它有效

 每个子集都有一个由其最大激活值确定的唯一分数。 通过按降序处理值，我们确保当我们计算值 a[i] 的贡献时，任何被计算的子集中仍然不会出现更高的值。 可除性结构保证激活仅依赖于局部乘法闭包，因此可以通过基于除数的分解独立地计算对固定最大值有贡献的子集。 这可以防止重复计算并确保每个子集都被准确分配一个贡献最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    vals = list(enumerate(a, start=1))
    vals.sort(key=lambda x: -x[1])

    maxn = n + 1
    divs = [[] for _ in range(maxn)]
    for i in range(1, n + 1):
        for j in range(i, n + 1, i):
            divs[j].append(i)

    pow2 = [1] * (n + 2)
    for i in range(1, n + 2):
        pow2[i] = (pow2[i - 1] * 2) % MOD

    used = [False] * (n + 1)
    res = 0

    for i, val in vals:
        cnt = 0
        for d in divs[i]:
            if not used[d]:
                cnt += 1

        if cnt:
            contrib = pow2[cnt - 1]
        else:
            contrib = 0

        res = (res + val * contrib) % MOD
        used[i] = True

    print(res)

if __name__ == "__main__":
    solve()
```该实现首先对索引进行排序，以便首先处理较大的值。 这保证了“最大优先”分解的正确性。 因为激活规则取决于乘法结构，所以为每个索引预先计算除数。 

这`used`数组跟踪哪些索引已被处理为潜在的最大值。 当评估索引 i 时，我们计算它的除数中有多少仍未使用。 这些代表通过选定的黑色集激活 i 的独立方法。 如果存在 cnt 这样的可用除数，则可以选择它们的任何非空子集来触发 i，这给出了 2^(cnt−1) 种可能性。 

最终的总和将每个值乘以它是最大激活元素的子集的数量。

 ## 边缘情况

 n = 1 的最小输入确认了基本贡献逻辑。 对于单个索引，唯一的子集是 {1}，并且它很容易变成黑色和绿色，因此分数等于 a[1]。 该算法处理索引 1，找到一个可用的除数，并分配贡献 2^0 = 1，匹配所需的输出。 

当所有值都相等时，每个索引都会按某种顺序处理，但排序可确保确定性处理。 由于贡献仅取决于除数结构，而不取决于价值关系，因此每个指数的贡献都是独立的。 该算法仍然为每个索引准确地分配一个有效的子集配置，以匹配对称性。 

在 n = 4 且值为 [1, 2, 4, 8] 的情况下，可分链是密集的。 较高的指数在早期处理后可用的除数较少，贡献也相应减少。 该算法正确地考虑了这样一个事实：一旦除数索引被处理，它就不能再充当后续索引的触发器，从而确保没有子集被多次计数。
