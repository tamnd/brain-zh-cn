 ## 解决方案

 ## 问题理解

 我们在无限网格上得到一个起点，并通过固定的循环依次生成一系列特殊点。 下一个点是通过将坐标乘以常量并添加偏移量从前一个点获得的，因此这些点形成了一个确定性的递增序列，该序列快速偏离原点。 

角色从给定位置开始，并且时间有限。 以曼哈顿距离计算，在网格中移动一个单位需要一秒钟，每当角色恰好到达一个特殊点时，就可以立即收集它。 任务是确定在时限内可以收集的这些生成点的最大数量，角色可以按任何顺序访问它们。 

关键结构是，虽然坐标可能非常大，但有用点的数量很少，因为序列由于乘数至少为 2 而呈指数增长。这意味着只有前几十个点可能是相关的，因为距离很快就会超过时间限制。 

时间限制允许原始值大小最多 10^16 次操作，但任何最佳解决方案都必须避免在大前缀上进行成对最短路径计算。 相反，我们依赖于候选点很少并且可以直接枚举的事实。 

当起始位置已经在节点上时，会出现微妙的边缘情况。 应立即对该节点进行计数，而无需花费时间，并且如果不包含该节点，则可能会改变所有最佳路径。 当最佳策略不遵循索引顺序时，就会出现另一个极端情况，因为按顺序访问节点可能比重新排列它们要糟糕得多。 

## 方法

 直接的暴力方法将考虑每个可能的节点子集和每个可能的访问顺序。 对于每个排列，我们模拟在点之间行走并检查总距离是否在时间限制内。 这是正确的，因为它显式地评估所有有效路由，但即使对于中等前缀大小也是不可能的，因为排列数量呈阶乘增长。 

问题的结构排除了大多数节点的考虑。 由于坐标呈倍增增长，因此从起点到节点 i 的距离迅速增加。 经过一些索引后，即使单独到达一个节点也已经超过了时间限制，因此任何解决方案只需要考虑节点的前缀，通常少于40个。 

一旦我们将自己限制在一个小的前缀上，我们就可以利用一个贪婪的想法：我们尝试每个可能的节点作为起点，然后在两个方向上向外扩展，总是从任一侧选择下一个最接近的可到达节点。 关键的观察结果是，二维曼哈顿空间中一维点序列上的最佳路线减少为尝试按排序索引顺序排列的连续段，但具有灵活的方向选择。 

我们不考虑排列，而是按索引顺序固定左边界和右边界，并计算从初始位置开始收集该段中所有节点的最小成本。 逐步扩展分段可确保我们仅保持线性过渡，从而避免重新计算完整路径。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 全排列搜索 | O(n!) | O(n) | 太慢了|
 | 前缀+区间扩展 | O(n^2) | O(n^2) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们首先生成节点序列，直到坐标变得非常大或超出安全范围（通常约为 40 个节点）。 这已经足够了，因为超过该点，距离就会超出任何可能的时间限制，并且无法对答案做出贡献。

接下来，我们迭代这个截断列表中所有可能的起始位置。 每个起点定义一个初始收集的节点和等于距起始位置的曼哈顿距离的当前时间成本。 

从该起始节点开始，我们尝试在其周围扩展一个窗口 [l, r]。 在每一步中，我们决定是向左还是向右扩展，从当前边界的两个可能移动中选择更便宜的一个。 成本是使用从当前位置到候选节点的曼哈顿距离来计算的。 

每次扩展时，我们都会更新花费的总时间并检查它是否仍在限制内。 如果是，我们用当前时间间隔内收集的节点数更新最佳答案。 

我们对所有起始索引重复此过程，确保隐式覆盖所有可能的连续间隔和所有可能的扩展方向。 

正确性来自于这样一个事实：一小组点上的任何最佳路线都可以转换为按照与递增或递减索引边界一致的顺序访问这些点的路径。 由于我们总是从连续区间扩展并贪婪地尝试两个方向，因此我们永远不会错过任何子集的有效最小成本遍历。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def generate(x0, y0, ax, ay, bx, by, xs, ys, t):
    pts = []
    x, y = x0, y0
    while True:
        if abs(x - xs) + abs(y - ys) <= t:
            pts.append((x, y))
        if x > 2e16 or y > 2e16:
            break
        x = ax * x + bx
        y = ay * y + by
    return pts

def dist(p, q):
    return abs(p[0] - q[0]) + abs(p[1] - q[1])

x0, y0, ax, ay, bx, by = map(int, input().split())
xs, ys, t = map(int, input().split())

pts = generate(x0, y0, ax, ay, bx, by, xs, ys, t)

ans = 0

for i in range(len(pts)):
    time = dist((xs, ys), pts[i])
    if time > t:
        continue
    l = r = i
    cnt = 1
    best = cnt

    while True:
        left_cost = float('inf')
        right_cost = float('inf')

        if l > 0:
            left_cost = dist(pts[l], pts[l - 1])
        if r + 1 < len(pts):
            right_cost = dist(pts[r], pts[r + 1])

        if left_cost == float('inf') and right_cost == float('inf'):
            break

        if left_cost < right_cost:
            nxt = l - 1
            new_cost = time + left_cost
            if new_cost > t:
                break
            l = nxt
            time = new_cost
            cnt += 1
        else:
            nxt = r + 1
            new_cost = time + right_cost
            if new_cost > t:
                break
            r = nxt
            time = new_cost
            cnt += 1

        best = max(best, cnt)

    ans = max(ans, best)

print(ans)
```代码的第一部分仅构建可能可达的节点的前缀。 它利用的观察结果是，一旦坐标爆炸超出时间限制，其他节点就不再重要。 

第二部分尝试将每个节点作为起始锚点。 从那时起，它维护一个窗口并贪婪地向更近的相邻节点扩展。 这模拟了遍历排序结构，同时始终采用本地最便宜的扩展，这是有效的，因为所有节点都位于一维索引链上。 

一个微妙的细节是，我们动态地重新计算截断列表中相邻节点之间的曼哈顿距离，而不是依赖于预先计算的全局距离。 这可以避免溢出并保持实现简单。

 ## 边缘情况

 当起始位置与第一个节点重合时，算法必须在任何移动逻辑开始之前立即对其进行计数。 在这样的情况下`(1,1)`开始于`(1,1)`，未能正确初始化收集的计数会导致计数少一。 

当时间极小时，即使存在附近节点，也只能收集起始节点。 在验证第一步成本之前，扩展循环不得尝试移动，否则它会错误地假设可达性。 

当坐标增长太快时，后面的节点将被完全忽略。 例如，如果`ax = ay = 100`，第三个或第四个节点可能已经无法从任何合理的起始位置到达，并且截断确保我们永远不会将它们包含在搜索空间中。
