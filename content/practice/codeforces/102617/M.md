 ## 解决方案
 ## 问题理解

 我们有一个日历，其中一周可以有任意天数`1`到`r`。 对于选定的周长`k`，日历被绘制为行`k`细胞。 我们画画`n`连续几天，观察这些细胞形成的连接形状。 当两幅画可以移动以重叠另一幅画而不旋转或改变形状时，两幅画被认为是相同的。 

任务是计算在尝试每个可能的周长度后可以出现多少种不同的连接形状`1`到`r`。 

约束条件允许`n`和`r`一样大`10^9`。 对所有可能的周长度进行模拟是不可能的，因为即使迭代到`10^9`值已经太慢了，构建日历单元格需要更多的工作。 解决方案必须将问题减少到恒定数量的算术运算。 

棘手的部分是理解不同的周长实际上何时会产生不同的形状。 一个常见的错误是假设每一个可能的起始位置或每周的长度总是给出一个新的形状。 这夸大了许多案例。 

考虑`n = 3, r = 4`。 正确答案是`4`。 对于一周的长度`1`,`2`,`3`， 和`4`，可能的形状有四种不同的形状。 如果粗心地计算每个可能的起始单元，则会计数更多，因为多个起始单元会产生相同的平移形状。 

另一种极端情况是周长至少为涂漆天数。 例如，`n = 3, r = 5`和`k = 5`。 三个绘制的单元格始终排成一排，无论它们从哪里开始。 这周长度贡献的答案只有一种形状。 计算所有起始位置会错误地添加五个形状。 

最小的情况也很重要。 为了`n = 1`，每个有效的日历宽度都会产生完全相同的单单元格形状。 答案是`1`， 不是`r`。 

## 方法

 直接的方法是检查每个可能的周长`k`。 对于每个`k`，我们可以尝试一周中的每个起始位置并构建所得的绘制单元格集，然后将其与之前看到的形状进行比较。 这是正确的，因为它从字面上列举了所有可能性。 然而，最多可以有`10^9`选择`k`，所以即使是单独的外循环也太慢了。 

关键的观察是我们实际上不需要绘制日历。 唯一重要的是一周的长度和绘画天数之间的关系。 

假设一周的长度是`k`。 

如果`k < n`，绘制的区域覆盖了不止一排。 在这种情况下，每个不同的有效起始偏移量都会创建不同的形状，并且恰好有`k`可能的形状。 

如果`k >= n`，所绘制的日期可以排成一行。 每个可能的起始位置只是同一行的移动副本，因此只有一种形状。 

所有周长的贡献都可以用数学方法计算。 为了`k = 1`到`min(r, n - 1)`，我们添加`k`形状。 如果`r >= n`，我们为所有宽度添加一个额外的形状`n`向前。 这变成了一个简单的算术级数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(r * n) | O(n) | 太慢了|
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`n`和`r`对于当前的测试用例。 

答案仅取决于这两个值，因此不需要构建日历。 
2.让`x = min(r, n - 1)`。 

这些周长小于`n`。 他们每个人都贡献了一些等于其自身价值的形状。 
3. 添加总和`1 + 2 + ... + x`到答案。 

这会计算绘制的日期跨越多行的每种情况。 
4. 如果`r >= n`， 添加`1`到答案。 

所有一周的长度从`n`继续创建相同的直线水平形状，因此它们一起只贡献一个额外的形状。 
5. 输出结果。 

最大中间值约为`5 * 10^17`，它很适合 Python 整数。 

为什么它有效：

 对于每个可能的一周长度，只有两种情况。 当周比绘制的段短时，第一个绘制的单元格可以占据周中的每个位置，并且每个位置给出独特的形状。 当周至少与所绘制的段一样长时，整个绘画是一行并且平移消除了起始位置的影响。 这些情况恰好覆盖了每个可能的日历宽度一次，因此总和会计算每个有效的形状，而不会重复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, r = map(int, input().split())

        x = min(r, n - 1)

        cur = x * (x + 1) // 2

        if r >= n:
            cur += 1

        ans.append(str(cur))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```变量`x`代表严格小于绘制长度的所有周长度。 表达式`x * (x + 1) // 2`是他们贡献的算术级数之和。 

条件`r >= n`处理第二种情况，即所有较大的日历都折叠成一个水平形状。 通过使用这里很容易犯一个相差一的错误`r > n`， 但`k = n`已经属于单行情况，必须包含在内。 

Python 整数避免了固定宽度整数类型语言中可能发生的溢出问题，因为乘法可以达到大约`10^18`。

 ## 边缘情况

 对于`n = 1`和`r = 100`，算法集`x = min(100, 0) = 0`，所以算术和没有任何贡献。 自从`r >= n`，它添加了一种形状。 这正确地处理了每个可能的日历都会产生相同的单个绘制单元的事实。 

为了`n = 3`和`r = 4`，该算法使用`x = 2`并计数`1 + 2 = 3`多行形状。 然后它又添加了一种形状，因为宽度`3`和`4`两者都将所有绘制的单元格放在一排中。 结果是`4`，避免将每个起始位置视为唯一而导致的重复计数错误。 

为了`n = 5`和`r = 5`，周长度完全等于绘制长度由`r >= n`健康）状况。 前四个宽度贡献`1 + 2 + 3 + 4 = 10`，和宽度`5`贡献了一个水平形状，给出`11`。 使用`r > n`这里会错过这个边界情况。
