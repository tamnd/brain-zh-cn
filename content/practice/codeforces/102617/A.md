 ## 解决方案
 ## 问题理解

 该问题模拟了游戏中的一对一比赛。 Chloe 有一个当前等级，并且她与另一位具有给定等级的玩家进行比赛。 获胜者获得失败者评分的 10% 作为获得积分，而失败者则失去自己评分的 10%。 给定评分和比赛结果，我们需要在比赛结束后计算 Chloe 的评分。 

输入包含 Chloe 的当前等级、对手的当前等级以及描述 Chloe 获胜还是失败的字符。 输出是 Chloe 应用评级更改后的新评级。 

评级可以大到$10^9$。 由于只有很少的算术运算，因此数字的大小是唯一重要的。 使用模拟、搜索或重复计算的方法会增加不必要的工作。 需要恒定时间解决方案，因为输入大小不包含要处理的大序列。 

一个常见的错误是总是减去 Chloe 评分的 10%。 只有当克洛伊输了时，这才是正确的。 当克洛伊获胜时，获得的金额改为来自对手的等级。 

例如，如果输入是：```
1000
1200
w
```正确的输出是：```
1120
```粗心的解决方案可能会计算$1000 + 100$，因为它使用 Chloe 自己的评分作为积分来源。 正确的增益是对手评级的 10%，即 120。 

另一个边缘情况是输给弱得多的对手。 为了：```
100
900
l
```输出是：```
90
```失败是基于克洛伊自己的评分，而不是对手的评分。 使用对手的评分会错误地减去 90 分，而不是 10 分。 

## 方法

 直接的强力方法是尝试对整个评级系统进行建模或搜索可能的评级变化，直到达到最终值。 这是不必要的，因为匹配只有一个状态转换。 唯一可能的操作是增加对手 10% 的评级，或者删除 Chloe 当前评级的 10%。 任何执行多个算术运算的方法都会解决比给定问题更难的问题。 

关键的观察是评级更新规则是确定性的。 赢家的收益和输家的损失已经用数学方法描述了，所以可以直接计算答案。 问题结构不需要数据结构、迭代或模拟。 我们只需要根据比赛结果选择正确的公式即可。 

蛮力之所以有效，是因为只有一种可能的比赛结果需要评估，但与直接公式相比，它会产生不必要的开销。 观察到评级变化仅取决于两个当前评级和输赢特征，从而将整个问题简化为恒定时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(k) 其中 k 是不必要的模拟工作 | O(1) | O(1) | 原则上太慢|
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取克洛伊的等级、对手的等级以及结果角色。 这三个值包含确定下一个评级所需的所有信息。 
2. 如果Chloe获胜，计算对手评分的10%并将其添加到Chloe的评分中。 克洛伊获得的分数是从对手那里获得的，因此对手的评分就是用于增加的值。 
3. 如果 Chloe 输了，计算 Chloe 当前评分的 10% 并从她的评分中减去。 失败的玩家将放弃自己评分的 10%。 
4. 打印结果评级。 

为什么它有效：

 该算法的不变性是，在精确应用问题描述的匹配规则后，存储的评分值始终是 Chloe 的评分。 胜利会根据对手的贡献改变她的评分，失败会根据她自己的贡献改变她的评分。 由于这是仅有的两种可能的转换，因此该算法涵盖了每个有效情况并应用了确切的所需更新。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    c = int(input())
    o = int(input())
    result = input().strip()

    if result == "w":
        c += o // 10
    else:
        c -= c // 10

    print(c)

if __name__ == "__main__":
    solve()
```前两行将两个评级读取为整数。 Python 整数处理可能的情况$10^9$值安全，无需担心溢出。 

条件检查匹配结果。 对于胜利，附加金额根据对手的评级计算。 由于所有评分均可被 10 整除，因此整数除以 10 即可得到准确的分数。 对于损失，减法是基于 Chloe 的当前评级。 

在失败的情况下，操作顺序很重要。 删除的金额必须根据更新前 Chloe 的评分来计算。 将公式写为`c -= c // 10`保留该行为，因为右侧是在赋值之前评估的。

 ## 边缘情况

 对于Chloe战胜更强对手的情况，比如：```
1000
1200
w
```算法进入 win 分支并添加`1200 // 10`，产生 1120。对两种结果使用 Chloe 评级的解决方案在这里会失败，因为它只会添加 100。 

对于 Chloe 输给评级相差很大的对手的情况：```
100
900
l
```算法进入损失分支并减去`100 // 10`。 对手的评级与此计算无关，因此结果为 90。这会捕获在计算每个更改时错误使用对手评级的实现。 

对于同等评级：```
5000
5000
w
```该算法将 500 分相加并返回 5500。相同的算术之所以有效，是因为获胜者和失败者的值恰好相等，从而确认这种情况不需要特殊处理。
