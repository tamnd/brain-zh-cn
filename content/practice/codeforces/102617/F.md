 ## 解决方案
 ## 问题理解

 该问题描述了一组必须放入矩形烤盘中的圆形饼干。 每个 cookie 都有一个坐标平面上的中心和一个半径。 平底锅的边必须与坐标轴平行，并且我们需要完全包含每个饼干的矩形的尽可能小的面积。 

一个有中心的饼干`(x, y)`和半径`r`达到`r`从其中心向左、向右、向上和向下单位。 这意味着包含一个 cookie 的最小矩形具有水平范围`[x - r, x + r]`和垂直范围`[y - r, y + r]`。 答案是覆盖所有这些单独范围的矩形面积。 

输入尺寸可以达到`100000`cookie，因此算法必须处理每个 cookie 恒定的次数。 比较每对 cookie 的二次方法将执行大约`10^10`最大的情况下的操作，远远超出了正常比赛的时间限制。 约束指向线性扫描。 

主要的边缘情况来自于忘记平底锅必须包含整个饼干，而不仅仅是其中心。 一个cookie就可以确定答案。 例如：```
1
0 0 5
```正确的输出是：```
100
```平底锅必须有宽度`10`和身高`10`。 仅跟踪中心的方法会错误地返回区域`0`。 

另一个常见错误是错误地处理负坐标。 考虑：```
2
-10 -5 2
4 3 1
```水平限制是`[-12, -8]`和`[3, 5]`，所以总宽度是`17`。 垂直极限是`[-7, -3]`和`[2, 4]`，所以高度是`11`。 正确的输出是：```
187
```仅使用正值或对坐标应用绝对值的粗心实现可能会丢失真正的最小和最大位置。 

最后的边界情况是所有 cookie 重叠时：```
3
0 0 1
0 0 1
0 0 1
```正确的输出是：```
4
```平底锅不需要为重复的饼干而变大。 只有极端的边界才重要。 

## 方法

 蛮力的想法是尝试可能的矩形并检查每个饼干是否适合每个矩形。 这是正确的，因为最终会考虑最佳矩形，但没有有用的方法来枚举所有可能的矩形。 可能的坐标数量随着输入值的增加而增加，因此即使对于中等数量的 cookie，这种方法也是不可能的。 

更自然的暴力解释是通过重复将每个 cookie 与其他 cookie 进行比较来找到最左、最右、最低和最高 cookie 边界。 这种方法之所以有效，是因为答案仅取决于极值。 然而，如果有`n`cookie，我们反复寻找极端，工作就变成了`O(n^2)`，这意味着关于`10^10`比较`n = 100000`。 

关键的观察结果是最终的矩形完全由四个数字决定。 左边是最小值`x - r`，右边是最大的值`x + r`，底边是最小值`y - r`，并且顶边是最大值`y + r`。 每个cookie都可以独立更新这四个值。 

蛮力方法之所以有效，是因为它最终找到了这四个边界，但它会多次重复相同的比较。 观察到每个 cookie 只提供四个候选边界，这让我们可以用单次传递来代替重复搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化代表当前平移边界的四个变量。 左侧和底部边界从正无穷大开始，因为我们正在搜索更小的值。 右边界和上边界从负无穷大开始，因为我们正在寻找更大的值。 
2.读取每个cookie并计算其四个极值坐标：`x - r`,`x + r`,`y - r`， 和`y + r`。 这些是唯一可以影响最终平底锅的值。 
3. 使用这四个值更新当前边界。 最小的左边缘和下边缘成为新的下限，而最大的右边缘和上边缘成为新的上限。 
4.处理完所有cookie后，计算宽度为`right - left`和高度为`top - bottom`。 他们的产品是尽可能最小的平底锅面积。 

工作原理：处理完 cookie 的任何前缀后，存储的四个边界准确地描述了包含迄今为止看到的所有 cookie 的最小矩形。 当添加新的 cookie 时，唯一可能的变化是它扩展了这四个边之一。 由于每个 cookie 都会被处理并考虑所有可能的扩展，因此最终边界包含每个 cookie 并且无法进一步减少。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    left = float('inf')
    right = -float('inf')
    bottom = float('inf')
    top = -float('inf')
    
    for _ in range(n):
        x, y, r = map(int, input().split())
        
        left = min(left, x - r)
        right = max(right, x + r)
        bottom = min(bottom, y - r)
        top = max(top, y + r)
    
    width = right - left
    height = top - bottom
    
    print(width * height)

if __name__ == "__main__":
    solve()
```该代码仅保留当前答案的四个边框。 价值观`x - r`和`x + r`描述 cookie 的左点和右点，同时`y - r`和`y + r`描述底部和顶部点。 

使用`float('inf')`负无穷大可以避免对第一个 cookie 进行特殊处理。 然后通过相同的更新逻辑处理每个输入值。 

Python整数具有任意精度，因此最终的乘法不需要特殊的溢出处理。 宽度和高度的计算必须在所有更新之后完成，因为面积取决于完整的 cookie 集而不是任何单独的 cookie。

import sys
import io

def solution(inp: str) -> str:
    data = inp.strip().split()
    if not data:
        return ""
    
    it = iter(data)
    n = int(next(it))
    
    left = float('inf')
    right = -float('inf')
    bottom = float('inf')
    top = -float('inf')
    
    for _ in range(n):
        x = int(next(it))
        y = int(next(it))
        r = int(next(it))
        left = min(left, x - r)
        right = max(right, x + r)
        bottom = min(bottom, y - r)
        top = max(top, y + r)
    
    return str((right - left) * (top - bottom))

 ## 边缘情况

 对于单 cookie 的情况：```
1
0 0 5
```该算法从空边界开始。 唯一的 cookie 将所有四个面更改为`-5`和`5`。 所得矩形的面积`100`，这是可能的最小平底锅。 

对于负坐标：```
2
-10 -5 2
4 3 1
```第一个 cookie 贡献左边缘`-12`和底边`-7`。 第二个 cookie 贡献右边缘`5`和顶边`4`。 最终的矩形是`17`单位宽度和`11`单位高，所以答案是`187`。 该算法不会特别处理负位置，因为比较自然会处理它们。 

对于重叠的 cookie：```
3
0 0 1
0 0 1
0 0 1
```每个 cookie 都会产生相同的边框。 最小和最大操作在第一个 cookie 之后保持矩形不变，给出正确答案`4`。 这说明了为什么解决方案取决于极端情况而不是 cookie 的数量。
