 ## 解决方案
 ## 问题理解

 有一排小屋，每个小屋都容纳一定数量的人。 小屋等距分布，输入给出每个小屋的人口数。 现有的冰淇淋店也位于同一条线上的给定坐标处。 

我们需要选择一个新商店的坐标。 只有当新商店比每个现有商店更靠近他们的小屋时，人们才会从新商店购买东西。 目标是通过为新商店选择最佳位置来找到可以捕获的最大小屋总人口。 

小屋和现有商铺数量均可达20万间。 这立即排除了检查每个可能的位置并将其与所有小屋进行比较的可能性，因为新商店有无限多个可能的真实坐标。 即使检查每一对小屋和商店也太慢了。 我们需要一个接近线性或基于排序的解决方案，围绕$O(n \log n)$。 

关键难点就在“严”字。 如果新商店与小屋的距离与现有商店的距离完全相同，则该人不算在内。 将区间视为闭区间的解决方案会高估答案。 

例如：```
Input
2 1
5 7
100

Output
7
```小屋位于位置 0 和 100，现有商店位于 100。第二个小屋与现有商店的距离为 0，因此永远无法赢得。 只能占领第一个小屋。 如果不小心实现，允许平局可能会错误地计算两个小屋。 

另一种边缘情况是几个小屋具有相同的最佳可能区域。```
Input
3 1
2 5 6
169

Output
7
```第一个小屋和第二个小屋都可以通过将新商店放置在左侧附近来占领。 第三个小屋不能。 仅检查现有商店旁边的位置的解决方案可能会错过最佳点，因为最佳位置可以是连续区间内的任何位置。 

## 方法

 一个直接的方法是为新店尝试每一个有意义的位置。 在两个连续的现有商店之间，喜欢新商店的人的集合不会连续变化，除非穿过一些小屋被捆绑的点。 我们可以生成许多候选点，针对每个小屋测试每个候选点，并保留最大值。 

这在概念上是有效的，因为答案必须来自通过距离比较创建的区域之一。 然而，候选者的数量可能很大，并且对照所有小屋检查每个候选者会导致远远超出允许的操作。 在最坏的情况下，这会变成二次或更糟。 

有用的观察是扭转观点。 不要询问所选商店位置可以占领哪些小屋，而是询问所选小屋允许在哪里放置新商店。 

假设一个小屋位于坐标$c_i$。 让$d_i$是从这个小屋到最近的现有商店的距离。 新商店在以下时间赢得了这座小屋：$$|x-c_i| < d_i$$这意味着：$$c_i-d_i < x < c_i+d_i$$因此，每个小屋都提供了一个开放的位置间隔，新商店将占领该小屋。 问题变成了寻找重叠开区间的最大总权重。 

这是一个加权扫描线问题。 我们在间隔开始时创建一个事件，在间隔结束时创建另一个事件。 唯一的微妙之处是正确处理开区间。 在同一坐标处，结束于该处的间隔在开始于该处的间隔变为活动之前消失，因为两者都不包含边界本身。 处理某个坐标处的所有事件后，当前总和表示紧邻该坐标之后的覆盖范围。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$或者更糟|$O(n)$| 太慢了|
 | 最佳|$O((n+m)\log m)$|$O(n+m)$| 已接受 |

 ## 算法演练

 1. 对现有的所有冰淇淋店的坐标进行排序。 对于每个小屋，我们需要知道它最近的商店，并且在排序列表中可以通过二分搜索找到它。 
2. 对于每个小屋，找出到最近的现有商店的距离。 如果小屋坐标是$c$距离是$d$，新商店只能在开放区间内占领这个小屋$(c-d,c+d)$。 
3.忽略小屋所在的地方$d=0$。 它们的间隔长度为零，因为现有的商店已经恰好位于小屋位置。 
4. 添加开始事件$c-d$和结束事件$c+d$。 事件的权重是该小屋中的人数。 
5. 对所有事件坐标进行排序。 对于每个坐标，首先删除以该坐标结束的间隔，然后添加从该坐标开始的间隔。 处理完该坐标处的所有事件后，当前权重是在接下来的开放段中捕获的人数。 
6. 跟踪扫描过程中看到的最大当前重量。 

为什么它有效：

 每个小屋都准确地贡献了所有位置的集合，在该集合中，新商店将击败该小屋的每个现有商店。 所选位置捕获的总人数恰好是包含该位置的所有区间的权重之和。 扫描线为连续事件坐标之间的每个可能区域维护该总和。 由于该值只能在事件坐标处发生变化，因此检查每个此类区域可以找到最佳位置。 

## Python 解决方案```python
import sys
import bisect

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    people = list(map(int, input().split()))
    shops = list(map(int, input().split()))
    shops.sort()

    events = []

    for i in range(n):
        pos = i * 100
        idx = bisect.bisect_left(shops, pos)

        best = 10**18
        if idx < m:
            best = min(best, abs(shops[idx] - pos))
        if idx > 0:
            best = min(best, abs(shops[idx - 1] - pos))

        if best > 0:
            events.append((pos - best, 1, people[i]))
            events.append((pos + best, -1, people[i]))

    events.sort()

    ans = 0
    cur = 0
    i = 0
    while i < len(events):
        x = events[i]

        while i < len(events) and events[i][0] == x[0] and events[i][1] == -1:
            cur -= events[i][2]
            i += 1

        j = i
        while j < len(events) and events[j][0] == x[0]:
            j += 1

        while i < j:
            cur += events[i][2]
            i += 1

        ans = max(ans, cur)

    print(ans)

if __name__ == "__main__":
    solve()
```首先对商店坐标进行排序，因为随后可以通过二分搜索来回答一条线上的最近邻居查询。 小屋坐标不需要单独存储，因为小屋$i$总是在坐标处$100i$使用从零开始的索引时。 

区间生成是核心变换。 与最近的现有商店的距离准确地决定了新商店可以移动多远，同时仍然是首选商店。 由于间隔是开放的，因此零距离不会创建有效位置并被跳过。 

扫描顺序是最有可能导致差一错误的部分。 结束事件必须在同一坐标处的开始事件之前应用。 如果首先处理开始，则两个接触间隔，例如$(-1,0)$和$(0,1)$会错误地显示在坐标零处重叠。 

Python 整数是任意精度的，因此可能的大总体总和不需要任何特殊处理。

 ## 边缘情况

 当现有商店正好位于小屋中时，到最近的商店的距离为零。 区间变空，算法将忽略它。 例如：```
2 1
5 7
100
```第二个小屋无法被占领，因为它到现有商店的距离已经为零。 扫描仅接收来自第一个小屋的间隔并返回 5。 

当两个间隔接触边界时，算法不得同时对两者进行计数。 例如，一间小屋可能允许在$(-10,0)$而另一个则允许持仓$(0,10)$。 坐标零本身不满足这两个区间，因此答案不能包含两个权重。 在开始事件之前处理结束事件会保留此规则。 

当同一区域可以捕获许多小屋时，扫描会自然累积它们的权重。 在第一个样本中，前两个小屋的间隔重叠，因此它们的人口合并为最终答案 7。
