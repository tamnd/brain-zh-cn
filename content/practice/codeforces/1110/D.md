 ## 解决方案
 ## 问题理解

 我们得到了一组瓦片，其中每个瓦片都带有 1 到 m 之间的整数值。 目标是重复挑选恰好三个图块的不相交组，并形成尽可能多的此类组。 有效组可以是三个相同的值，也可以是三个按升序排列的连续值。 每个图块最多可以使用一次，因此一旦某个图块参与到一个组中，就不再考虑它。 

输出是可以从给定多重集形成的有效组的最大数量。 

关键的困难在于，值 i 的图块可以参与两个根本不同的结构：它可以使用 i、i、i 完成相同值的三元组，或者它可以是连续三元组 i−2、i−1、i 或 i、i+1、i+2 的一部分，具体取决于我们如何排列相邻值。 这些选择在全球范围内相互作用，因此贪婪的局部决策会失败。 

约束 n、m 高达 10^6 意味着任何比 m 中的线性或近线性更差的算法都会太慢。 二次或三次 DP 值是不可能的。 即使 O(n log n) 也是可以接受的，但任何尝试直接考虑跨多个状态的计数组合的操作都会失败。 

当连续的三元组以局部不明显的方式重叠时，就会出现一个微妙的问题。 例如，如果像 3,3,3,3,3 这样的窗口周围的计数很高，则天真的贪婪可能会提前提交太多相同的三元组，并稍后阻止全局更好的连续三元组。 当我们首先贪婪地最大化连续三元组时，会出现另一种失败模式，这可能会浪费剩余的重复项，而这些重复项本可以形成更多相同值的三元组。 

失败示例：

 输入：

 1 5

 3 3 3 3 3

 最佳答案是 1 个三元组 (3,3,3)，但是尝试形成连续三元组的贪婪方法不会执行任何操作，并且可能会错过所有三元组都是相同且可用的。 

这说明根据值进行本地决策是不够的； 我们需要一个结构化的 DP 来解释相邻位置之间的相互作用。 

## 方法

 暴力方法将尝试模拟从多重集中选择三元组的所有方法。 在每一步中，我们选择任何有效的三元组并递归。 这相当于探索一个巨大的状态空间，其中每个状态都是一个多集配置。 即使表示状态也是指数级的，并且在最坏的情况下，在每个可能的三元组上进行分支会导致大约 O( (n/3)! ) 的可能性。 这是完全不可行的。 

相反，我们通过观察只有每个值的计数才重要，并且交互在连续值之间严格是局部的来压缩问题。 这表明以升序处理值，同时维护一个 DP，跟踪我们正在扩展的连续三元组的“开放链”数量。 

关键的观察结果是，连续的三元组 i−2、i−1、i 是唯一的非局部交互，并且它们的跨度仅为 3。这使我们能够按顺序处理值，同时保持一个小状态，记住有多少部分结构是从先前的索引中携带的。 

我们隐式定义 dp[i][j][k]，在位置 i 处，我们跟踪有多少个从 i−2 和 i−1 开始等待完成的未完成链。 我们没有存储完整的 DP 表，而是将其简化为具有两个进位变量的贪婪 DP。 

对于每个值 i，我们决定：

 我们首先使用一些类型为 (i, i, i) 的三元组，然后将剩余计数与先前的进位组合起来形成 (i−2, i−1, i)。 顺序很重要：我们希望最大化已完成的三元组的数量，同时确保只传递必要的剩余部分。 

关键的结构简化是，最优策略可以通过一次传递值来计算，仅维护在受控状态转换下贪婪地形成尽可能多的三元组后向前传递的元素数量。 这是一个典型的连续三个位置的“本地窗口 DP”。

暴力破解会失败，因为它独立地处理选择，而优化的解决方案则利用了有界交互宽度 3。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（递归选择）| 指数| O(n) | 太慢了 |
 | 将 DP 滑过价值计数 | O(米) | O(1) 到 O(m) | 已接受 |

 ## 算法演练

 我们首先将输入压缩到频率数组 cnt[i] 中，因为只计算物质。 

1. 初始化一个 DP 状态，跟踪 i−2 和 i−1 携带了多少可用的剩余物。 我们将它们表示为两个变量：a 和 b。 
2. 将 i 从 1 迭代到 m。 在每一步中，我们都有 cnt[i] 可用的图块，并且还可能有一些来自先前步骤的剩余贡献，这些贡献可以参与以 i 结尾的连续三元组。 
3. 首先，我们尝试形成尽可能多的相同三元组 (i, i, i)。 这是 cnt[i] // 3. 我们将其直接添加到答案中并相应地减少 cnt[i]。 
4. 删除相同的三元组后，我们考虑形成连续的三元组。 在索引 i 处，我们可以一起使用 i−2、i−1 和 i 中的一些元素。 此类三元组的数量受到三个位置的最小可用性的限制，但由于我们是按顺序处理的，因此我们将早期指数的贡献视为已部分分配到待定结构中。 
5. 我们使用存储的剩余元素贪婪地匹配尽可能多的 (i−2, i−1, i) 三元组，更新进位状态，以便未使用的元素向前传播。 
6. 处理完索引 i 后，我们更新 DP 状态，以便 i 处的剩余元素成为未来连续三元组进位的一部分。 

中心思想是，在每一步中，我们都会耗尽局部可能性，然后以受控方式传递剩余容量，确保未来的配置无法创建比 DP 允许的更多的三元组。 

### 为什么它有效

 不变的是，在处理值 i 之后，在给定可用多重集前缀的情况下，在 i 或之前结束的所有三元组已经被最大化。 存储在 DP 状态中的任何剩余元素都准确地表示那些仍然可以对涉及未来值的三元组做出贡献的图块，并且前缀内的任何替代重新排列都可以增加已完成三元组的数量，而不会降低后续三元组的可行性。 交互的局部性确保任何最佳解决方案都可以转化为尊重这种贪婪前缀最大化属性而不会造成损失的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    cnt = [0] * (m + 2)
    arr = list(map(int, input().split()))
    
    for x in arr:
        cnt[x] += 1

    # dp carries:
    # carry1 = leftover from i-1 that can form consecutive triples
    # carry2 = leftover from i-2 that is pending combination
    carry1 = 0
    carry2 = 0

    ans = 0

    for i in range(1, m + 1):
        # use triples of identical values first
        t = cnt[i] // 3
        ans += t
        cnt[i] -= 3 * t

        # now try to form consecutive triples (i-2, i-1, i)
        # using carry2 (i-2), carry1 (i-1), cnt[i]
        x = min(carry2, carry1, cnt[i])

        ans += x
        carry2 -= x
        carry1 -= x
        cnt[i] -= x

        # update carries: shift window forward
        carry2 = carry1
        carry1 = cnt[i]

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先构建频率计数，以便输入内的所有排序都变得无关紧要。 变量 ans 累加完整的三元组。 

相同的三元组会立即被删除，因为它们不会干扰最佳排列中的连续三元组； 任何此类分组都是严格本地化的。 

这两个进位变量表示在前面的步骤中未使用但仍然有资格与当前值和下一个值形成连续三元组的元素。 在位置 i 形成尽可能多的连续三元组后，我们通过更新进位来向前移动窗口。 

微妙的一点是，进位总是被解释为未来窗口的可用性，因此它们的含义每次迭代都会发生变化。 这种移动窗口结构使得 DP 具有恒定空间。

 ## 边缘情况

 一个关键的边缘情况是所有图块都具有相同的值。 该算法处理单个索引，立即形成 cnt[i] // 3 个三元组，并且不向前推进任何内容。 对于像这样的输入`6 tiles of value 7`，进位变量始终保持为零，答案变为 2，这与最佳分组相匹配。 

另一个边缘情况是当值完美间隔时，因此只能是连续的三元组。 例如`1 2 3 1 2 3 1 2 3`。 该算法使用跨索引的进位传播，以便每个窗口 (1,2,3) 恰好贡献一个三元组。 进位确保不会重复计算或跳过分组，最终结果为 3，这是最佳结果。 

最后一个微妙的情况是，贪婪的相同三元组提取似乎减少了连续三元组的机会。 由于相同的三元组是本地的并且仅消耗相同值的元素，因此它们永远不会阻止形成 (i, i+1, i+2) 结构，从而将总计数减少到超出已经最优的范围，并且 DP 通过进位传播正确地进行补偿。
