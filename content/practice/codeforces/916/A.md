 ## 解决方案
 ## 问题理解

 我们有 24 小时制的起床时间和固定的时间间隔`x`几分钟后。 杰米在起床前的某个未知时间设置了闹钟。 闹钟响后，他每隔一段时间就重复小睡一次。`x`分钟，直到准确到达唤醒时间。 

我们不是直接选择闹钟时间，而是逆向思考。 假设设置了闹钟`y`在起床之前小睡。 那么闹钟时间正是`y * x`目标时间前几分钟。 每次小睡都会将时间向前移动`x`分钟，所以之后`y`按一下，闹钟在起床时刻到达。 

唯一的限制是初始闹钟时间必须是“幸运的”，这意味着当写入时`hh:mm`格式，至少一位数字是`7`。 我们需要最小的非负数`y`这样如果我们回去`y * x`从 24 小时循环时钟上的唤醒时间算起的分钟数，结果时间包含`7`数字。 

约束非常小：时钟状态空间只有 24 * 60 = 1440 种可能的时间。 贪睡步骤最多 60 分钟，因此即使对所有可能的情况进行完整的强力扫描`y`在环绕并重复一个循环之前，值只会触及几千个状态。 这立即排除了对对数或高级数据结构的任何需要； 线性模拟就足够了。 

主要的微妙之处在于时间在午夜前后结束。 从 回来`00:00`1 分钟后降落在`23:59`。 任何忘记模运算的解决方案都会产生不正确的负时间。 

另一个常见的错误是在向前发现幸运时间时提前停止，而不是从起床时间向后推理。 条件是关于_开始闹钟时间_，而不是中间延后时间。 

## 方法

 最直接的想法就是从唤醒时间向后模拟这个过程。 对于每个可能的小睡次数`y = 0, 1, 2, ...`，我们计算时间`y * x`唤醒时刻前的分钟数，并检查该时间是否包含数字`7`。 

这种强力视图已经接近最佳，因为每次检查的时间复杂度为 O(1)，并且时钟每 1440 分钟重复一次。 最多 1440 / gcd(1440, x) 步骤后，该过程进入一个循环并重新访问较早的时间。 自从`x ≤ 60`，这个周期长度很小，在最坏的情况下，我们在重复之前最多检查几百或几千个状态。 

关键的观察结果是，只有 1440 个不同的时钟状态，因此即使检查一个完整周期内所有可能的向后偏移也是安全的。 我们不需要推理无限的时间或大的界限； 我们只是搜索通过重复减法生成的有限周期序列`x`分钟。 

因此，最佳解决方案就是这种在几分钟内进行模块化运算的受控模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | y 的暴力模拟 | O(1440 / x) | O(1) | O(1) | 已接受 |
 | 与模块化时钟算法相同的模拟| O(1440) 最坏情况 | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从 00:00 开始在几分钟内完成工作，以简化整个过程。 

1. 将起床时间换算为总分钟数`t = hh * 60 + mm`。 这为所有时间算术提供了单一线性标度。 以分钟为单位的工作避免了重复处理小时-分钟的界限。 
2. 初始化`y = 0`。 这表示没有小睡，这意味着我们首先检查唤醒时间本身是否已经是有效的启动闹钟时间。 
3. 重复执行以下操作：将候选警报时间计算为`(t - y * x) mod 1440`。 Modulo 1440 确保我们保持在 24 小时周期内，正确处理午夜的环绕。 
4. 将该候选项转换回小时和分钟形式。 提取数字并检查这四个字符中是否有一个包含`'7'`。 
5. 如果条件成立，则返回`y`立即地。 Since we iterate`y`in increasing order, the first valid value is guaranteed to be minimal.
 6. 否则递增`y`并重复。 

关键的结构思想是我们正在有限状态空间上遍历确定性循环。 每增量`y`准确地移动`x`分钟向后，所以我们探索模 1440 时钟图的单个轨道。 

### 为什么它有效

 每个值`y`正好对应一个可能的闹钟时间：时间`y * x`起床前几分钟。 因为时间以 1440 为模进行循环，所以增加`y`遍历时钟状态的重复序列。 由于总共只有 1440 个状态，因此该序列最终必须重复，这意味着所有可到达的候选状态都位于有限循环中。 

通过扫描`y`按照递增顺序，我们按照递增贪睡计数的确切顺序检查闹钟时间。 因此，第一次满足“包含数字 7”条件的时间是最小有效的暂停次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def has_seven(h, m):
    return '7' in f"{h:02d}{m:02d}"

def solve():
    x = int(input())
    hh, mm = map(int, input().split())

    start = hh * 60 + mm

    for y in range(0, 2000):
        t = (start - y * x) % 1440
        h = t // 60
        m = t % 60
        if has_seven(h, m):
            print(y)
            return

solve()
```该解决方案将时间转换为分钟，以简化减法和环绕处理。 循环结束`y`由一个足够大的常量安全地限制以覆盖所有可能的循环； 2000 已经足够了，因为状态空间只有 1440。 

辅助函数通过将时间格式化为固定宽度字符串来检查数字条件，确保保留前导零，这对于以下情况是必要的`07:xx`。

 ## 边缘情况

 一个常见的边缘情况是唤醒时间本身已经很幸运了。 例如，`00:07`与任何`x`应立即返回`0`。 该算法处理这个问题是因为它检查`y = 0`在进行任何减法之前。 

另一个微妙的例子是穿越午夜。 如果起床时间是`00:00`我们减去分钟，我们必须降落在`23:xx`正确。 模 1440 算术确保负结果包含在正确的上日间隔中，因此不需要特殊处理。 

最后一种情况是循环在几次迭代后重新访问同一时间。 由于搜索空间是有限的，算法最终将遍历所有可达状态。 因为我们在第一个有效出现处停止，所以重复不会影响正确性，它只会限制运行时间。
