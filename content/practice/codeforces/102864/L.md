 ## 解决方案
 ## 问题理解

 该问题描述了一个建筑物可以重复升级的游戏。 第一次升级费用`N1`金子。 每次升级都会变得更加昂贵，因为将之前的成本乘以`P`，而每次升级总是增加相同固定数量的每小时黄金产量`M`。 对于选定的升级号`Q`，我们需要计算仅从该升级中额外生产黄金所需的时间，以收回该升级所花费的黄金。 

的成本`Q`-th 升级是一个几何级数术语。 第一次升级费用`N1`，第二个成本`N1 × P`，以及第 Q 次升级成本`N1 × P^(Q-1)`。 由于第 Q 次升级的好处只是额外的`M`每小时产生的金币，答案是升级成本除以`M`。 

测试用例数量可以达到100个，但是`Q`最多为 50。这意味着该问题不需要高级优化。 即使每次升级执行少量工作的方法也足够快。 主要困难是正确处理几何增长和浮点精度，因为`P`是有理数，最终答案必须保留一位小数。 

当升级号是第一次升级时，粗心的实施可能会失败。 例如，使用输入`1000 1.2 100 1`，答案是`10.0`，因为第一次升级正好花费 1000 金币。 一个公式使用`P^Q`而不是`P^(Q-1)`会错误地计算`12.0`。 

另一个常见错误出现在以下情况：`P`等于`1`。 用于输入`1000 1 100 50`，每次升级仍然需要花费1000金币，所以恢复时间为`10.0`。 任何假设该值必须增长并重复相乘而不考虑起始项的实现都可能产生不正确的结果。 

## 方法

 一种直接的方法是模拟升级成本。 从第一次升级成本开始`N1`，然后将成本乘以`P`确切地`Q-1`次达到Q次升级。 获得该成本后，将其除以`M`。 这是可行的，因为每次乘法都会从几何级数的一项移动到下一项。 

暴力模拟在这里已经很有效了，因为`Q`限制为 50。最坏情况下每个测试用例仅执行 49 次乘法。 如果有数百万次升级，重复乘法将成为不必要的工作，但给定的限制使这种方法完全足够。 

更数学化的方法使用几何级数的封闭形式。 第 Q 次升级成本为`N1 × P^(Q-1)`，所以我们可以直接计算幂并除以`M`。 这减少了操作数量并更清楚地表达了关系，尽管由于约束很小，实际差异很小。 

关键的观察是我们不需要计算任何先前的升级。 恢复时间仅取决于当前升级的成本和固定产量增加，因此所有早期的升级成本都无关紧要。

 ## 算法演练

 1. 阅读`N1`,`P`,`M`， 和`Q`对于当前的测试用例。 这些值描述了初始升级成本、增长率、产量增加和目标升级数量。 
2. 将第 Q 次升级的成本计算为`N1 × P^(Q-1)`。 指数是`Q-1`因为第一次升级已经具有原始成本并且尚未发生乘法。 
3. 将计算出的升级成本除以`M`。 这给出了从这次升级中获得额外生产以偿还所花费的黄金所需的小时数。 
4. 打印结果，保留一位小数。 浮点运算就足够了，因为该问题保证双精度类型可以处理所需的范围。 

为什么有效：成本序列恰好是几何级数。 第一项是`N1`，并且以下每一项都是通过乘以产生的`P`。 因此，第 Q 项恰好有`Q-1`应用乘法。 恢复时间的定义就是当前的升级成本除以额外的每小时收入，因此计算出的值与所需的数量相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        N1, P, M, Q = input().split()
        N1 = int(N1)
        P = float(P)
        M = int(M)
        Q = int(Q)

        cost = N1 * (P ** (Q - 1))
        ans.append(f"{cost / M:.1f}")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```输入一次处理一个测试用例，因为用例之间不存在依赖性。 这些值经过仔细转换：`N1`,`M`， 和`Q`是整数，而`P`必须存储为浮点数，因为它可以包含小数值。 

指数使用`Q - 1`，这是问题中的主要边界条件。 什么时候`Q`为 1，幂变为零，Python 正确计算`P ** 0`为 1，则成本等于`N1`。 

最终的格式化使用`:.1f`，匹配所需的输出精度。 Python 浮点运算就足够了，因为最大可能的指数只有 49。

 ## 边缘情况

 当`Q`是 1，没有乘法`P`。 用于输入`1000 1.2 100 1`，算法计算`1000 × 1.2^0`，即`1000`，然后除以`100`，生产`10.0`。 一个公式使用`P^Q`会错误地添加一个额外的增长步骤。 

什么时候`P`为1时，等比级数变为常数列。 用于输入`1000 1 100 50`，算法计算`1000 × 1^49`，剩下的就是`1000`。 恢复时间依然`10.0`，表明该解决方案不依赖于成本增加。 

当升级数量较大时，比如`1000 1.3 1000 50`，重复乘法和直接取幂都是安全的，因为最大指数仅为 49。该算法直接计算最终项并避免不必要的中间值存储。
