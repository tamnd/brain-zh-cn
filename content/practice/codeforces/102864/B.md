 ## 解决方案
 ## 问题理解

 货架上包含按固定顺序排列的 M 个产品。 每个产品都有重量和价值。 龙龙只能按照这个顺序沿着货架移动，所以他选择的产品必须形成原始序列的子序列。 

购物车的最大重量为 N。特殊规则是第一个之后选择的每个产品不得比紧邻其之前选择的产品重。 换句话说，如果所选产品的权重为g1、g2、g3，那么它们必须满足g1 >= g2 >= g3。 在总权重不超过N的所有有效选择中，我们需要最大可能的总价值。 

限制很小，N 和 M 最多为 100。具有一个额外维度的普通背包解决方案就足够了，但枚举所有可能子集的方法是不可能的。 可以有 100 个产品，这会产生 2^100 种可能的选择，远远超出了时间限制内可以探索的范围。 

一些细节很容易导致错误的答案。 选择的第一个产品之前没有重量限制，因此它可以有任何重量。 例如：```
5 2
5 10
1 1
```正确答案是 11，因为两种产品都可以选择。 错误地初始化先前权重的解决方案可能会拒绝第一个产品或无法使用空状态。 

另一种情况是较重的产品稍后出现：```
5 3
1 10
3 100
2 5
```正确答案是 105，选择重量 3 和 2。重量为 1 的产品不能在它们之前选择，因为货架上的顺序无法更改。 像普通背包变体那样按重量对产品进行分类的解决方案将解决不同的问题并产生无效的结果。 

最后的边缘情况是不选择任何内容：```
1 1
1 7
```答案是 7，因为产品适合。 如果容量为零，则答案将为 0，因此动态规划必须始终保留空选择。 

## 方法

 最直接的方法是尝试所有可能的产品子集。 对于每个子集，我们检查所选索引是否保持原始顺序、权重是否不增加以及总重量是否适合购物车。 此方法是正确的，因为每个可能的选择都会被检查，但它有 2^M 个子集。 当 M = 100 时，最坏的情况需要大约 1.27 × 10^30 次检查，这是不可能的。 

有用的观察是，未来仅取决于已加工产品的两条信息。 我们需要知道当前的总重量，因为它决定了剩余的容量，并且我们需要知道最后选择的产品的重量，因为它控制是否允许下一个产品。 

这将问题转化为动态规划。 从左到右扫描产品时，我们为已用容量和最后选择的重量的每种组合保持最佳值。 在加工产品时，我们要么跳过它并保留旧状态，要么在其重量不超过先前选择的重量时接受它。 

第一个选择的产品需要特殊处理，因为没有先前的重量。 我们用比每个可能的产品权重更大的特殊先前权重来表示空状态，从而允许选择任何产品作为第一个。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^M × M) | O(2^M × M) | O(M)| 太慢了|
 | 最佳 | O(M × N × 101) | O(N × 101) | 已接受 |

 ## 算法演练

 1. 初始化动态规划表。`dp[c][w]`表示处理货架的某些前缀后可实现的最大值，使用总重量`c`，最后选择的产品有权重`w`。 特殊状态`w = 101`代表到目前为止什么都不选择。 

初始状态是`dp[0][101] = 0`，因为在取出任何产品之前，购物车的重量为零，并且对第一个产品没有限制。 

1. 从左到右处理每件产品。 对于当前有重量的产品`g`和价值`s`，创建当前状态的副本来表示跳过此产品的选项。 

必须考虑跳过，因为所选择的产品只需是一个子序列，而不是货架的连续部分。 

1. 对于每个现有状态，尝试采用当前产品。 如果当前状态有之前的权重`w`和`g <= w`，可以添加产品。 使用新容量更新状态`c + g`和新的最后重量`g`。 

最后选择的权重变为`g`因为每个未来的产品都必须与最近添加的产品进行比较。 

1. 所有产品处理完毕后，无论最终使用的容量或最后选择的重量如何，答案都是所有有效状态中的最大值。 

为什么它有效：

 动态编程状态准确地存储了未来决策所需的信息。 已处理相同前缀并具有相同使用容量和最后选择的重量的两个不同选择对于每个剩余产品具有相同的可能性。 只保留其中较大的值并不能消除最优解。 每个转换都会考虑产品仅有的两个选择，跳过它或在允许时接受它，因此每个有效的子序列都会被表示。 最终所有状态中最大的就是最佳有效的购物计划。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    items = [tuple(map(int, input().split())) for _ in range(M)]

    NEG = -1
    dp = [[NEG] * 102 for _ in range(N + 1)]
    dp[0][101] = 0

    for g, s in items:
        new_dp = [row[:] for row in dp]

        for weight in range(N + 1):
            for last in range(102):
                if dp[weight][last] == NEG:
                    continue
                if g <= last and weight + g <= N:
                    new_dp[weight + g][g] = max(
                        new_dp[weight + g][g],
                        dp[weight][last] + s
                    )

        dp = new_dp

    ans = 0
    for weight in range(N + 1):
        for last in range(102):
            ans = max(ans, dp[weight][last])

    print(ans)

if __name__ == "__main__":
    solve()
```该表有 102 个可能的先前重量，因为实际产品重量从 1 到 100，索引 101 保留用于空选择。 价值`NEG`标记无法到达的状态，防止使用无效的转换。 

对于每个产品，代码都会在应用转换之前复制旧表。 这可以防止在一次迭代中多次使用相同的产品，这与 0/1 背包更新前一层的状态的原因相同。 

条件`g <= last`强制执行不增加重量的要求。 空状态有`last = 101`，因此任何第一个产品都会被接受。 容量检查在更新之前进行，以防止超出购物车限制的状态进入表中。 

所有值都很容易适合 Python 整数，因为最大可能的总值仅为 10000。

 ## 边缘情况

 对于第一个边缘情况：```
5 2
5 10
1 1
```初始状态是`(capacity = 0, last = 101)`。 可以选择第一个产品，因为 5 小于 101，创建一个容量为 5、最后重量为 5、值为 10 的状态。可以选择第二个产品，因为 1 小于 5，创建最终答案 11。特殊的空状态允许第一个产品不受限制。 

对于订购边缘情况：```
5 3
1 10
3 100
2 5
```在第一个产品之后，最佳状态的最后权重为 1。第二个产品的权重为 3，因此它无法遵循该状态。 该算法仍然保持空状态，允许第二个产品成为第一选择。 然后第三个产品可以跟随它，因为 2 小于 3。答案变为 105，这尊重原始的货架顺序。 

对于无选择边界：```
0 1
1 7
```唯一可到达的状态是空购物车。 该产品永远不会满足容量条件，因为添加它会产生重量 1，超出了限制。 最大剩余值为0，这是正确的结果。
