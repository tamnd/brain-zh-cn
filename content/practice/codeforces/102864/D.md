 # 问题理解

 我们有一棵树，每个顶点都分配了一个值。 对于两个给定的顶点 p 和 q，我们需要查看它们之间唯一路径上的每个顶点，将它们的所有指定值相乘，并计算该乘积的欧拉 totient 函数。 由于乘积可能非常大，因此只需要对 998244353 取模的结果。 

重要的是我们永远不需要产品本身。 如果一个数被写为素数分解，欧拉函数仅取决于出现的素数及其总指数。 对于素因数分解

 [
 x=\prod p_i^{e_i}
 ]

 我们有

 [
 \phi(x)=\prod p_i^{e_i-1}(p_i-1)。 
]

 顶点数量最多为 100000 个。遍历许多路径或以昂贵的方式重复分解值的解决方案将不符合两秒的限制。 我们需要一个顶点数量接近线性的解决方案。 由于每种颜色最多有 1000000 个，因此可以预处理所有可能的素因数。 

路径可以包含所有顶点，所以我们需要处理的信息量也是O(n)。 有用的观察结果是只有一个查询。 我们不需要重树算法，例如重轻分解或质心分解。 

一些边缘情况可能会破坏简单的实现。 如果路径仅包含一个顶点，则答案是该单一颜色的全部。 例如：```
1 1 1
1
```乘积为 1，答案为 1。假设每个素数贡献都有一个因子 p-1 的公式将错误地产生零。 

另一个问题是重复素因数。 考虑：```
2 1 2
4 4
1 2
```路径积为16，即(2^4)，所以答案为(2^3(2-1)=8)。 只记录素数是否出现而忽略其指数的方法会计算出错误的结果。 

第三种情况是不同的顶点贡献相同的素数。 例如：```
3 1 3
6 10 15
1 2
2 3
```乘积为 900，即 (2^2 3^2 5^2)，答案为 (2\cdot3\cdot5=30)。 单独计算每个节点的因子并将各个个体相乘将会失败，因为欧拉函数对于非互质数不能进行乘法运算。 

## 方法

 直接的方法是首先找到从p到q的路径上的顶点，将它们的颜色相乘，然后计算totient。 路径可以包含 100000 个顶点，颜色可以是 1000000 个，因此产品本身可以有数十万个数字。 将其存储为整数是不可能的。 

更好的暴力破解版本可以将产品作为一个因素计数。 我们可以分解每种颜色并添加路径上出现的每个素数的指数。 这已经足够了，因为最终答案仅取决于这些总指数。 

剩下的问题是如何快速分解许多数字。 每种颜色的试分割都太慢了。 由于最大颜色只有1000000，我们可以使用筛法构建最小素因子表。 之后，每次分解都会重复去除当前数的最小质因数。 

查找路径也很简单，因为树只被查询一次。 从 p 开始的深度优先搜索可以存储每个顶点的父顶点，直到到达 q。 跟随父指针重建确切的路径。 树结构消除了对更高级路径查询技术的需要。 

暴力破解的想法之所以有效，是因为答案仅取决于一条路径的节点。 当它试图直接代表巨大的产品时，它会失败。 质数指数足够的关键观察将整个任务减少为路径恢复加上快速因子计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(路径长度×产品尺寸) | O(产品尺寸) | 太慢了|
 | 最佳 | O(n + max(c) log log max(c) + 总因子数) | O(n + 最大(c)) | 已接受 |

 ## 算法演练

 1. 为 1000000 以内的每个数字构建一个最小素因数数组。这样可以将每个颜色值分解为素数，而无需重复试除。 
2. 从 p 运行 DFS 并存储每个节点的父节点。 当找到 q 时停止。 从 q 回到 p 的父链正是所需的路径，因为一棵树在两个顶点之间只有一条简单路径。 
3. 遍历恢复的路径。 对于每个顶点颜色，重复使用最小素因子表来提取素因子并将其指数添加到频率图中。 
4. 答案从 1 开始。对于总指数为 e 的每个素数，将答案乘以 (p^{e-1}(p-1)) 模 998244353。这直接将欧拉公式应用于完整路径乘积。 

为什么它有效：

 路径重建步骤是正确的，因为树中的每一对顶点都有一条路径。 因子计数步骤是正确的，因为数字相乘会加上它们的素数指数，因此将每个顶点的指数相加就可以得到整个路径乘积的因式分解。 最后的乘法将欧拉 totient 函数的定义应用于该因式分解，因此每个素数与其组合指数只贡献一次。 

## Python 解决方案```python
import sys
from collections import defaultdict

input = sys.stdin.readline

MOD = 998244353
MAXC = 1000000

def solve():
    n, p, q = map(int, input().split())
    colors = list(map(int, input().split()))

    graph = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    spf = list(range(MAXC + 1))
    for i in range(2, int(MAXC ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, MAXC + 1, i):
                if spf[j] == j:
                    spf[j] = i

    parent = [-2] * n
    parent[p - 1] = -1
    stack = [p - 1]

    while stack:
        u = stack.pop()
        if u == q - 1:
            break
        for v in graph[u]:
            if parent[v] == -2:
                parent[v] = u
                stack.append(v)

    cnt = defaultdict(int)
    cur = q - 1
    while cur != -1:
        x = colors[cur]
        while x > 1:
            prime = spf[x]
            cnt[prime] += 1
            x //= prime
        cur = parent[cur]

    ans = 1
    for prime, exp in cnt.items():
        ans = ans * pow(prime, exp - 1, MOD) % MOD
        ans = ans * (prime - 1) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```筛子创建最小的素因子表。 作业`spf[x] = x`最初将每个数字视为素数，然后合数通过发现的最小除数进行更新。 

DFS 不需要深度信息或子树数据。 它只记录前趋，因为查询要求一条路径。 搜索后，从 q 移动到`parent`只访问每个路径顶点一次。 

因子计数循环会仔细计算重复因子。 例如，当颜色为 8 时，循环会提取 2 三次，而不是将其视为仅出现一次。 

最后的循环直接应用 totient 公式。 Python 整数不会溢出，但在每次运算后仍使用模乘法来保持值小且高效。

 ## 边缘情况

 对于单个顶点路径，DFS 立即找到目标，并且父链仅包含该顶点。 当颜色为 1 时，因子计数器保持为空，因此答案保持为 1，匹配 (\phi(1))。 

对于重复的素数幂，例如两种颜色等于 4 的路径，算法不会计算 (\phi(4)\times\phi(4))。 相反，它创建组合因式分解 (2^4) 并计算 (\phi(16)=8)，这是所需的操作。 

对于相同素数以多种不同颜色出现的路径，频率图会在应用最终公式之前合并这些贡献。 这避免了假设欧拉函数与任意因子相乘的常见错误。
