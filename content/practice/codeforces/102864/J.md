 ## 解决方案
 ## 问题理解

 河流是一长串位置，每个位置都恰好含有一种炼金材料。 ErvinX​​ie可以选择从哪里开始，然后继续前进，收集他经过的每一个材料。 收集到的材料不需要按照收集时的顺序放置。 唯一的要求是，最终的收藏必须包含足够多的魔法阵所需的每种材料类型的副本。 

形成是通过一个数组来描述的`a`。 多次出现的材料`a`还必须多次收集。 河流由另一个数组描述`b`，其中每个元素都是在该位置找到的材料。 任务是找到河流的最短连续部分，其物质计数涵盖地层中所有所需的计数。 答案是该部分的长度。 如果不存在这样的部分，则答案是`DragonXie`。 

输入大小迫使近似线性的解决方案。 地层长度可达100万，河流长度可达200​​万。 检查每个起始位置并扩展段的解决方案需要围绕`s * len`最坏的情况下，大约有两万亿张支票无法完成。 即使是重复计算范围内材料的方法也太慢。 我们只需处理每条河流位置恒定的次数。 

不同材料类型的数量仅为`5000`，这意味着我们可以将频率信息存储在数组中，而不是使用较慢的结构。 小字母表大小有帮助，但是非常大的序列长度意味着我们仍然需要`O(len)`算法。 

一些边缘情况可能会破坏更简单的实现。 如果阵型需要重复的材料，只检查是否每种类型都出现是不正确的。 例如：```
1
3
1 1 2
4
1 2 1 2
```正确的输出是`3`因为该段`[1, 2, 1]`包含材料的两份副本`1`及材料一份`2`。 只记录类型是否出现的粗心解决方案会接受较短的无效段。 

另一种情况是整条河不够的时候：```
2
2
1 2
1
1
```正确的输出是`DragonXie`。 如果解决方案在找到一种所需材料后停止而不检查所有要求，则会产生错误的答案。 

最短的河段也可以是整条河流：```
1
4
1 1 1 1
4
1 1 1 1
```答案是`4`。 仅在发生收缩时更新答案的实现可能会错过这种情况。 

## 方法

 直接的做法是尝试河中每一个可能的起始位置。 对于每次启动，我们都会将段向右延伸，计算收集到的材料，并在满足所有所需数量时停止。 这是正确的，因为考虑了每个可能的段起点，并且每个起点的第一个有效端点给出了从那里开始的最短段。 

问题在于许多细分市场共享几乎相同的信息。 在最坏的情况下，地层可能需要一种永远不会出现在大河源头附近的材料。 强力扫描可以检查几乎所有可能的左右边界对。 和`len = 2 * 10^6`，操作次数可以接近`4 * 10^12`，远远超出了极限。 

关键的观察是所需的条件仅取决于当前段内的计数。 当一个段已经拥有足够的每种材料时，向右移动其左边界只会使其更短。 当某个片段缺少某些东西时，扩展正确的边界是获得更多材料的唯一方法。 这种单调行为允许滑动窗口。 

该窗口保留两个频率阵列：一个用于所需的地层，另一个用于当前的河段。 我们不会在每次更改后比较所有材料类型，而是维护一个表示仍缺少多少所需材料出现的值。 仅当该事件先前丢失时，添加材料才会降低该值。 仅当移除材料使段再次不足时，移除材料才会增加它。 

蛮力之所以有效，是因为它独立地检查所有段，但它重复几乎相同的计数工作。 滑动窗口在重用相邻段信息的同时保持相同的正确性，将问题简化为一次过河。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(len²) | O(k) | 太慢了|
 | 最佳 | O(长度) | O(k) | 已接受 |

 ## 算法演练

 1. 计算每种物质在地层中出现的次数。 让`missing`最初等于地层长度，因为尚未收集到所需的材料。 
2. 将右指针从河流的起点移动到终点。 将每个新材料添加到当前窗口的计数中。 如果在添加之前仍然需要该材料，请减少`missing`。 

的价值`missing`表示当前窗口仍缺少的所需材料副本的确切数量。 
3. 每当`missing`变为零时，当前窗口可以构建阵型。 在窗口保持有效的情况下向前移动左指针，用找到的每个较短的有效长度更新答案。 

删除不必要的材料总是安全的，因为目标是最短的有效段。 当再移除一种材料破坏有效性时，当前左边界是该右边界的最小可能值。 
4.处理完整条河流后，输出记录的最小长度。 如果没有找到有效的窗口，则输出`DragonXie`。 

为什么它有效：

 滑动窗口保持的不变量是`missing`始终等于当前窗口中缺少的所需材料副本的数量。 右指针只向前移动，每次窗口变得有效时，左指针都会删除所有可移动的材料，而不会失去有效性。 每个可能的最短线段都有一个到达其右边界的时刻，并且收缩过程找到其最小左边界。 由于检查了每个候选最短窗口，因此最终的最小值是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    k_line = input().strip()
    if not k_line:
        return
    k = int(k_line)

    s = int(input())
    need = [0] * (k + 1)

    arr = list(map(int, input().split()))
    for x in arr:
        need[x] += 1

    length = int(input())
    river = list(map(int, input().split()))

    have = [0] * (k + 1)
    missing = s
    left = 0
    ans = length + 1

    for right, x in enumerate(river):
        have[x] += 1
        if have[x] <= need[x]:
            missing -= 1

        while missing == 0:
            cur = right - left + 1
            if cur < ans:
                ans = cur

            y = river[left]
            if have[y] <= need[y]:
                missing += 1
            have[y] -= 1
            left += 1

    if ans == length + 1:
        print("DragonXie")
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```程序首先建立队形的频率表。 数组大小仅取决于材料类型的数量，因此即使序列很大，它仍然很小。 

变量`missing`被初始化为`s`，所需材料份数的总数。 当材料进入窗口时，只有当窗口之前的副本数量少于所需数量时才会有帮助。 额外的副本不能满足任何新的需求，因此它们不会改变`missing`。 

收缩循环仅在窗口有效时运行。 在删除最左边的材料之前，代码会检查该材料当前是否有助于满足要求。 如果计数仍在所需数量内，则删除它会创建丢失的副本。 检查和递减的顺序很重要，因为它决定删除的副本是否有用。 

两个指针最多从左向右各移动一次。 没有对河流进行重复扫描，这使实施保持在要求的范围内。

 ## 边缘情况

 对于重复的材料需求，算法会跟踪数量而不仅仅是存在。 在输入中```
1
3
1 1 2
4
1 2 1 2
```窗口将展开，直到包含两个副本`1`和一份`2`。 当窗户`[1,2,1]`已达到，`missing`变成零，答案变成`3`。 基于类型的解决方案会错误地认为`[1,2]`就足够了。 

对于不可能的队形，右指针最终到达河的尽头，而`missing`永远不会达到零。 在```
2
2
1 2
1
1
```窗口包含一种必需的材料，但仍然缺少材料`2`。 该算法从不记录答案和输出`DragonXie`。 

对于整条河流就是答案的情况，```
1
4
1 1 1 1
4
1 1 1 1
```右指针仅在收集到最后位置后才使窗口有效。 收缩阶段无法删除任何项目，因为每个副本都是必需的，因此记录的长度仍然保留`4`。 这避免了仅接受成功收缩后找到的答案的常见错误。
