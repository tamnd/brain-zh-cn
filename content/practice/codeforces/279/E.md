 ## 解决方案
 ## 问题理解

 一个美丽的数字是任何带有任一符号的二的幂。 换句话说，每个被加数必须是以下之一$$\pm 2^0,\ \pm 2^1,\ \pm 2^2,\dots$$我们给定一个正整数$n$，但不是十进制形式。 相反，它的二进制表示形式是作为长度可达一百万个字符的字符串提供的。 我们必须找到尽可能少的美丽数字，其总和等于$n$。 

另一种看待问题的方式是我们想写$$n=\sum_i d_i 2^i$$其中每个系数$d_i$选自$\{-1,0,1\}$。 每个非零系数都贡献一个美丽的数字，因此目标是最小化其中的位置数量$d_i \neq 0$。 

最显着的限制是输入长度。 二进制字符串可能包含$10^6$位，这意味着值$n$其本身就是一个天文数字般的巨大。 将其转换为整数是不可能的。 任何解决方案都必须直接作用于二进制表示。 

二次算法立即被排除。 甚至$O(|s| \log |s|)$当输入本身已经包含一百万个字符时是不必要的。 目标是线性扫描，每位仅需要恒定的额外工作。 

一些边缘情况很容易被错误处理。 

考虑输入：```
1
```号码已经是$2^0$，所以答案是：```
1
```假设每个表示都需要至少一个进位传播步骤的解决方案可能会意外地产生更大的值。 

考虑：```
111
```这是$7$。 

朴素的二进制表示使用三个幂：$$7=2^2+2^1+2^0$$但更好的分解是$$7=2^3-2^0$$仅使用两个被加数。 任何简单计算设置位的方法都会返回 3，而不是正确答案 2。 

另一个微妙的情况是一系列的情况：```
111111
```二进制权重是六，但是$$63=64-1$$只需要两个加数。 最佳解决方案必须能够有意地创建进位，因为这样做通常会减少非零系数的总数。 

## 方法

 最直接的想法是搜索所有可能的系数分配$-1$,$0$， 和$1$2 的幂并检查哪些组合之和为$n$。 这是正确的，因为每个有效的分解都对应于这样的分配。 

Unfortunately, even for a number with only$m$位，大致有$3^m$的可能性。 和$m$达到一百万，这是完全不可能的。 

下一个观察是二进制算术已经告诉我们系数如何相互作用。 假设我们从最低有效位向上处理数字。 在任何位置，低位唯一重要的信息是进位是否进入当前位置。 

这意味着整个问题可以表示为只有两种状态的动态程序：$$\text{carry} = 0 \quad \text{or} \quad \text{carry} = 1$$一点点$b$，我们知道值$$x = b + \text{carry}.$$我们必须选择一个数字$d \in \{-1,0,1\}$和一个新的进位，以便$$x = d + 2 \cdot \text{new\_carry}.$$每次$d$是非零的，使用了一个漂亮的数字。 

关键的见解是，未来仅取决于套利，而不取决于任何早期的选择。 这将指数搜索转变为对二进制字符串进行一次扫描的双状态 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(3^m)$|$O(m)$| 太慢了 |
 | 具有进位状态的最佳 DP |$O(m)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 反转二进制字符串，以便按从最低有效位到最高有效位的顺序处理位。 
2. 维持两个DP值：$$dp[0]$$是对当前后缀进行进位0处理后的最小成本。$$dp[1]$$是对当前后缀进行进位1处理后的最小成本。 
3.初始化：$$dp[0]=0,\quad dp[1]=\infty$$因为在处理任何位之前没有传入的进位。 
4. 对于每一位$b$：

 1. 创建一个新的数组$ndp$。 
2. 对于每个进位状态$c\in\{0,1\}$, 计算$$x=b+c.$$3. 枚举所有有效的分解$$x=d+2\cdot nc$$在哪里$d\in\{-1,0,1\}$。 
4.增加成本$1$如果$d\neq0$，否则添加$0$。 
5、放松相应的状态$ndp[nc]$。 
5. 所有位处理完毕后，可能仍存在最终进位。 
6. 如果末尾进位为0，则不需要额外的数字。 
7、如果最后进位为1，则表示多了一个系数$+1$在下一个二的幂处，贡献一个额外的被加数。 
8. 取最小有效最终成本。 

### 为什么它有效

 对于每个已处理的位置，DP 存储最小数量的非零有符号数字，这些数字可以准确生成该数字的已见过部分，同时为剩余的高位留下指定的进位。 

转换考虑了满足当前位方程的所有可能方法$$b+\text{carry}=d+2\cdot\text{new\_carry}.$$不排除任何有效的有符号二进制表示，并且每个表示都对应于此类本地选择的唯一序列。 由于 DP 始终保持每个进位状态的最小成本，因此最终答案恰好是漂亮加数的最小数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    INF = 10**18
    dp0, dp1 = 0, INF

    for ch in reversed(s):
        b = ord(ch) - ord('0')

        ndp0 = INF
        ndp1 = INF

        # carry = 0
        if dp0 < INF:
            x = b

            if x == 0:
                ndp0 = min(ndp0, dp0)
            else:  # x == 1
                ndp0 = min(ndp0, dp0 + 1)  # d = 1
                ndp1 = min(ndp1, dp0 + 1)  # d = -1

        # carry = 1
        if dp1 < INF:
            x = b + 1

            if x == 1:
                ndp0 = min(ndp0, dp1 + 1)  # d = 1
                ndp1 = min(ndp1, dp1 + 1)  # d = -1
            else:  # x == 2
                ndp1 = min(ndp1, dp1)      # d = 0

        dp0, dp1 = ndp0, ndp1

    answer = min(dp0, dp1 + 1)
    print(answer)

if __name__ == "__main__":
    solve()
```实现完全遵循 DP。 

这对`(dp0, dp1)`存储每个进位状态的最佳成本。 由于只有两种状态，因此即使输入包含一百万位，内存使用量也保持不变。 

转换逻辑直接来自求解$$x=d+2\cdot nc.$$的值只有三个可能$x$：0、1 和 2。每一个都有极少量的有效分解，因此每一位只需要不断的工作。 

最终的表达```
min(dp0, dp1 + 1)
```处理剩余的进位。 进位 1 表示附加系数$+1$下一个 2 的幂，这会多花费一个被加数。

 ## 边缘情况

 考虑输入```
1
```DP 开头为`(dp0, dp1) = (0, INF)`。 处理唯一的位`1`创建状态`(1, 1)`。 以进位 0 结束，成本为 1，而以进位 1 结束，则成本`1 + 1 = 2`。 答案是1，对应分解$1 = 2^0$。 

考虑```
111
```朴素的二进制表示使用三个被加数。 在 DP 处理期间，进位 1 状态比重复使用正系数更便宜。 最终答案变成2，对应$8 - 1$。 这证实了该算法正确地利用进位来减少非零数字的数量。 

考虑```
111111
```DP 以零额外成本不断地在整个 1 块中传播进位。 最后只求系数$-1$在最低位和最终进位生成$+1$保持。 答案是2，匹配$$63 = 64 - 1.$$这正是对设置位进行计数会严重失败的情况，而进位状态 DP 仍然以线性时间工作。
