 ## 解决方案
 ## 问题理解

 我们得到了一个由长度为 n 的数组组成的小型系统，该系统通过固定数量的全局转换而演化。 我们从一个数组开始`a`，并且我们重复应用精确`u`运营。 每个操作都会立即修改数组的每个元素，或者将其与固定数组组合`b`使用按位异或，或者根据给定的排列对数组进行排列`p`然后添加一个常数`r`。 

执行所有操作后，我们计算最终分数，该分数取决于结果数组以及两个附加数组`k`和`b`。 分数是与职位相加的，因此一旦最终值达到，每个指数都会独立贡献`a`是已知的。 

关键的结构困难在于操作是全局的和组合的：按顺序应用它们会产生异或变换、排列和加性移位的复杂混合。 自从`n ≤ 30`和`u ≤ 30`，我们处理的不是大数据，但如果我们尝试明确地跟踪所有可能性，那么我们正在处理指数状态空间。 该问题本质上是在有限域上组成少量类似线性的变换并评估最佳结果。 

排列和加法之间的相互作用产生了一个微妙的问题。 幼稚的实现可能会独立处理异或和排列，但排列会在未来添加的地方发生变化，因此顺序以非交换方式起作用。 另一个常见的陷阱是尝试将所有操作序列模拟为每个索引独立的； 但这会失败，因为指数在排列下混合，因此每个头寸的历史都依赖于其他头寸。 

朴素推理的一个具体失败案例是假设每个指数独立发展。 如果`p`是一个循环`1 → 2 → 3 → 1`，那么即使单个移位操作也会导致值旋转，这意味着索引的贡献`i`取决于整个周期历史，而不仅仅是局部更新。 

## 方法

 蛮力的想法是逐步模拟所有可能的操作序列并计算结果数组。 然而，问题不在于操作之间的选择，顺序是固定的。 真正的困难在于每个操作都会转换整个状态，因此暴力破解必须在每个步骤之后跟踪数组的完整状态。 

直接模拟是可行的，因为`n ≤ 30`和`u ≤ 30`。 我们可以显式地将每个操作应用于整个数组。 挑战在于我们还需要评估最终得分，这取决于数组之间的成对关系而不仅仅是最终值。 这表明不仅仅跟踪`a`，我们必须跟踪每个初始基本元素如何对最终结果做出贡献。 

关键的观察是由异或和加法引起的有限域结构的线性。 每个操作都是整数上向量空间的变换，具有两种类型的线性操作：异或的作用类似于 GF(2^k) 中的加法，排列是线性重新索引，加法是`r`引入了可以单独跟踪的恒定变化。 因为`u`很小，我们可以将系统建模为应用于每个初始位置的基础贡献的一系列变换。 

我们不是直接模拟所有可能的值，而是跟踪每个原始元素如何`a`对最终数组的贡献和加权的总贡献`k`和`b`。 这减少了在两个运算下维持基向量变换并计算最终加权和的问题。

 | ---| ---| ---| ---|
 | 全状态暴力模拟| O(nu) | O(n) | 已接受 |
 | 最佳线性贡献跟踪 | O(nu + n²u) | O(nu + n²u) | O(n²) | 已接受 |

 ## 算法演练

 我们将这个过程解释为维护每个初始指数对每个最终指数的贡献。 

1. 将当前状态表示为从原始索引到当前值的映射。 最初，每个位置仅对其自身做出贡献。 

这使我们能够将结构与值分开。 
2. 对于运算类型 1，对固定数组应用按位异或。 这意味着每个当前值都是通过与常数项结合来独立修改的，因此我们更新每个映射的值部分而不改变索引结构。 
3. 对于运算类型 2，应用排列，然后添加`r`。 排列步骤重新排列贡献：处于位置的每个贡献`i`移动到位置`p[i]`。 加法步骤将所有值增加`r`排列后统一。 
4. 重复`u`操作，维护结构映射和累积的恒定变化。 
5. 所有操作结束后，通过汇总贡献来计算最终得分：对于每个位置，将其最终值与`k[i]`并使用给定的评分规则累积到答案中。 

关键思想是排列影响结构，而异或和加法影响值。 将它们分开可以避免重新计算完整的历史记录。 

### 为什么它有效

 每个操作在状态空间上都是仿射的：排列是双射重新标记，异或是可逆线性操作，加法是统一转换。 由于这些操作的组成没有独立基础贡献之间的相互作用，因此跟踪每个初始索引的传播方式就足够了。 不会丢失任何信息，因为索引结构上的每个转换都是可逆的，因此映射完全确定最终值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, u, r = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    k = list(map(int, input().split()))
    p = list(map(int, input().split()))
    p = [x - 1 for x in p]

    # current value array
    cur = a[:]

    for _ in range(u):
        op = input().strip()
        if op == "1":
            for i in range(n):
                cur[i] ^= b[i]
        else:
            nxt = [0] * n
            for i in range(n):
                nxt[p[i]] = cur[i]
            for i in range(n):
                nxt[i] += r
            cur = nxt

    ans = 0
    for i in range(n):
        ans += cur[i] * k[i]

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案直接模拟该过程，因为`n`和`u`很小。 异或运算按元素应用，排列运算通过构造一个新数组来处理，其中每个元素根据`p`。 添加的`r`在排列后应用，尊重同时更新的要求。 

最终得分计算为加权总和：`k`。 不需要中间优化，因为约束对于完整模拟来说足够严格。 

## 工作示例

 ### 示例 1

 输入：```
3 2 1
7 7 7
8 8 8
1 3 2
1 2 3
```我们一步步模拟。 

| 步骤| 运营| 数组状态 |
 | ---| ---| ---|
 | 0 | 初始| [7,7,7]|
 | 1 | 与 b 异或 | [15, 15, 15] |
 | 2 | 排列 + r | [15+1, 15+1, 15+1] = [16, 16, 16] |

 最终成绩：```
16*1 + 16*3 + 16*2 = 96
```这表明排列不会改变均匀数组，但加法会均匀累积。

 最终成绩：```

 ## 边缘情况

 一种边缘情况是所有元素都相等。 在这种情况下，排列没有明显的效果，但异或和加法仍然适用。 该算法正确地保持了一致性，因为这两种操作在排列之前或之后都按元素进行，这不会改变相同的向量。 

另一个边缘情况是单元素数组。 排列变得微不足道，因此唯一的效果是重复应用异或和加法。 模拟自然地处理这个问题，因为索引退化为单个位置。 

最后一种情况是零操作。 最终答案必须直接从初始数组计算出来，无需任何转换。 该实现处理了这个问题，因为循环操作被完全跳过，并且最终的聚合使用原始的`cur`。
