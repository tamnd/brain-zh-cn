 ## 解决方案
 ## 问题理解

 我们得到一个数字$f$，我们考虑斐波那契规则生成的无限序列，但以 1013 为模。该序列从 0 和 1 开始，每个下一个值都是前两个值的和，模 1013 减少。因此，序列是完全确定的，并且随着时间的推移重复值，因为只有 1013 个可能的残基。 

任务不是完整计算序列本身，而是找到值所在的最早索引$f$出现。 如果该值从未出现在序列中，我们输出 -1。 

索引从零开始，因此位置 0 为 0，位置 1 为 1，位置 2 为 1，依此类推。 

关键约束是模数为 1013，它足够小，使得对的序列$(F_i, F_{i+1})$最终必须重复，暗示周期性行为。 然而，我们并没有被要求提供期限； 我们被要求第一次出现，这样可以进行简单的正向模拟。 

主要隐藏的细节是，虽然斐波那契模数是周期性的，但周期长度可能足够大，以至于必须仔细控制对所有对的完全枚举的天真思考。 尽管如此，1013 仍然足够小，存储访问过的状态或模拟有界前缀是可行的。 

出现微妙的边缘情况时$f = 0$。 第一个元素已经等于 0，所以答案立即为 0。另一个是$f = 1$，它出现在索引 1 处，并再次出现在索引 2 处，因此我们必须确保仅返回第一次出现的情况。 

一个不太明显的边缘情况是，并非所有值$[0, 1012]$必然出现在斐波那契数列模 1013 之前的周期重复之前。 所有残基都出现的天真假设会导致错误的无条件答案。 

## 方法

 最直接的方法是从索引 0 开始逐一生成以 1013 为模的斐波那契数，并在每一步检查当前值是否等于$f$。 由于序列是确定性的，因此最终会发现$f$或进入一个循环。 

这是有效的，因为每个项仅取决于前两个值，因此我们可以维护滚动对并向前迭代。 正确性是立即的：我们按升序检查每个位置，直到找到目标或确定我们已经看到足够的状态来结束重复。 

无界模拟的问题在于斐波那契模 1013 存在于大小为有限的状态空间中$1013 \times 1013$如果我们考虑有序对。 这保证了最终的重复，但在最坏的情况下，我们可能会在看到重复的对之前遍历一个长前缀。 不过，这个界限只有大约一百万个州，这是安全的。 

更结构化的观点是将状态视为成对的$(F_i, F_{i+1})$。 一旦一对重复，从该点开始的序列就会精确重复。 因此，当一对重复时，如果我们没有看到，我们可以停止模拟$f$，以后就不会再出现了。 

这将问题转化为对具有 1,013² 个状态的函数图的图遍历，其中每个状态都有一个后继者。 我们本质上是沿着自行车道行走，直到重复。 

访问对的哈希集让我们在检测到循环时立即停止。 由于我们最多仅存储 1,013² 状态，因此内存仍然安全。

 ## 算法演练

 我们在跟踪指数时维持以 1013 为模的斐波那契序列。 

1. 初始化两个代表连续斐波那契值的变量：$a = 0$,$b = 1$，和索引$i = 0$。 这对应于我们已经知道前两项的序列的开始。 
2.如果$a == f$，立即返回 0，因为索引 0 是第一次出现。 
3. 在我们没有超出安全范围的情况下进行迭代$1013^2 + 5$步骤，或者直到循环检测阻止我们。 
4. 在每次迭代时，比较$a$和$f$。 如果匹配，则返回$i$。 这确保我们始终报告最早出现的事件，因为我们按递增的索引顺序进行扫描。 
5. 在斐波那契数列中向前移动：计算下一个值$c = (a + b) \bmod 1013$。 
6.更新对：设置$a = b$,$b = c$，和增量索引$i$。 这保留了不变量$(a, b)$总是代表$(F_i, F_{i+1})$。 
7. 可选择跟踪访问过的对$(a, b)$。 如果一对重复，则停止并返回 -1$f$没有找到。 这确保了我们在进入循环后不会无限循环。 

### 为什么它有效

 在每一步，算法都保持不变式：$a = F_i \bmod 1013$和$b = F_{i+1} \bmod 1013$。 转换规则保留了这个不变量，因为斐波那契演化是确定性的。 由于对的序列存在于有限集合中，因此对的重复意味着该序列从该点开始变为周期性的。 因此，如果$f$不会出现在重复状态之前，也不会出现在之后，保证提前终止的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1013

def solve():
    f = int(input().strip())

    a, b = 0, 1
    if a == f:
        print(0)
        return

    # We store visited states of pairs (a, b)
    visited = set()
    visited.add((a, b))

    idx = 1

    # Safe upper bound: at most MOD^2 states
    limit = MOD * MOD + 5

    while idx <= limit:
        a, b = b, (a + b) % MOD

        if a == f:
            print(idx)
            return

        if (a, b) in visited:
            break
        visited.add((a, b))

        idx += 1

    print(-1)

if __name__ == "__main__":
    solve()
```该代码使用两个变量显式维护斐波那契转换，避免完整的数组存储。 指数`idx`正好对应的位置`a`在序列中，所以当我们比较时`a == f`，我们正在检查正确的序列位置。 

访问集可以防止进入循环后出现无限循环。 如果没有它，由于界限，循环在实践中仍然是安全的，但循环检测给出了一个干净的理论截止点。 

初始化检查`a == f`直接处理零索引，这是斐波那契实现中常见的差一陷阱。

 ## 边缘情况

 对于$f = 0$，算法在进入循环之前检查初始值。 自从$a = 0$在索引 0 处，它立即返回 0，与所需的第一个匹配项匹配。 

对于多次出现的值，例如$f = 1$，扫描顺序保证正确性。 第一个匹配发生在索引 1 处，即使存在后来的匹配，算法也会由于索引遍历的增加而立即停止。 

对于可能永远不会出现的值，例如模 1013 的某些余数，访问状态机制可确保终止。 一旦斐波那契对重复，序列就会进入与前一段相同的循环。 如果$f$在这次重复之前没有遇到过，未来的迭代不能引入它，所以返回 -1 是正确的。
