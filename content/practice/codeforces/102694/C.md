 ## 解决方案
 ## 问题理解

 我们有一棵树，有多达数十万个节点。 树懒从节点开始`a`并想要到达节点`b`。 唯一的限制是它最多可以跨越`c`入睡前的边缘。 如果路径从`a`到`b`短于或等于`c`，树懒到达`b`。 否则，它会完全停止`c`离开后的边缘`a`走在独特的道路上`b`。 

对于每个查询，我们需要输出树懒停止的节点。 输入是一棵树，后面跟着许多独立的移动查询。 树结构永远不会改变，因此主要的挑战是对其进行足够的预处理以快速响应每个动作。 

限制最多允许`n = 300000`节点和`q = 300000`查询。 针对每个查询遍历树的解决方案可能需要`O(nq)`最坏情况下的时间，远远超出了可能的范围。 在预处理阶段之后，我们需要每个查询的时间约为对数。 由于树的深度也可以是`O(n)`，除非我们准备更快的祖先查询，否则简单的父级跳转是不够的。 

棘手的情况来自运动方向。 目的地可能位于有根树中起始节点的上方、下方或另一个分支中。 例如：```
3
1 2
2 3
1
1 3 1
```正确的输出是：```
2
```粗心的实施可能只会从`a`并失败，因为道路是从向下开始的。 

另一种边缘情况是树懒已经拥有足够的能量时：```
3
1 2
2 3
1
1 3 5
```正确的输出是：```
3
```始终准确执行的实现`c`跳跃会尝试越过目的地。 

第三种情况是起始节点和结束节点相等：```
1
1
1 1 10
```答案是：```
1
```路径长度为零，因此不会发生移动。 假设路径至少包含一条边的解决方案可能会引入无效跳转。 

## 方法

 直接的解决方案是重建路径`a`到`b`，然后移动`c`沿着它的边缘。 这是正确的，因为树的每对节点之间只有一条简单路径。 然而，通过在树中搜索每个查询来找到该路径可以访问许多节点。 有一棵链状的树`300000`节点数和查询数相同，总工作量可以接近`90000000000`边缘访问，速度太慢。 

关键的观察是我们实际上并不需要整个路径。 我们只需要找到距一个端点一定距离的节点。 这是一个经典的跳树问题。 

我们对树进行生根并预处理二进制升降表。 对于每个节点，我们将其祖先存储在一定距离处`1, 2, 4, 8`， 等等。 这让我们可以向上移动任意数量的边`O(log n)`时间。 

为了处理向任意目标的移动，我们使用最低的共同祖先。 让`l`是以下的 LCA`a`和`b`。 路径从`a`到`b`分为两部分：来自的路径`a`最多`l`，以及来自的路径`l`下降到`b`。 

如果树懒需要移动的边少于距离`a`到`l`，答案就是简单的祖先`a`。 否则，它到达 LCA，然后继续向下到达`b`。 通过查看路径的反面，向下运动会转换为向上运动。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每次查询 O(n)，总共 O(nq) | O(n) | 太慢了 |
 | 二元提升| 预处理后每个查询的 O(log n) | O(n log n) | O(n log n) | 已接受 |

 ## 算法演练

 1. 在节点处建立树的根`1`并运行深度优先搜索。 存储每个节点及其直接父节点的深度。 执行此操作时，构建二进制升降台，其中`up[node][j]`是的祖先`node`那是`2^j`其上方的边缘。 

这张桌子让我们可以跳过大部分路径，而不是一边走一边走。 
2. 对于每个查询`(a, b, c)`，找到最低共同祖先`l`的`a`和`b`。 两个节点之间的距离为：`depth[a] + depth[b] - 2 * depth[l]`。 

如果这个距离最多为`c`，树懒到达`b`，所以答案是`b`。 
3. 如果树懒在到达 LCA 之前停下来，意味着`c <= depth[a] - depth[l]`, 跳跃`c`祖先自上而下`a`。 
4. 否则，树懒首先到达LCA。 剩余距离为：`remaining = c - (depth[a] - depth[l])`。 

路径的目标侧有长度`depth[b] - depth[l]`。 一个节点`remaining`LCA 下方的边缘朝向`b`与节点相同`depth[b] - depth[l] - remaining`上面的边缘`b`。 从向上跳`b`那个数量。 

为什么它有效：每个查询都使用树中的唯一路径来回答。 LCA 将这条路径分成两部分，一部分从`a`一个向下走向`b`。 二元提升准确地返回在选定数量的向上边缘之后到达的节点，因此可以在不重建路径的情况下处理两个可能的行进方向。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    graph = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        graph[u].append(v)
        graph[v].append(u)

    LOG = (n + 1).bit_length()
    up = [[0] * LOG for _ in range(n + 1)]
    depth = [0] * (n + 1)

    stack = [1]
    parent = [0] * (n + 1)
    parent[1] = 1

    while stack:
        u = stack.pop()
        up[u][0] = parent[u]
        for v in graph[u]:
            if v != parent[u]:
                parent[v] = u
                depth[v] = depth[u] + 1
                stack.append(v)

    for j in range(1, LOG):
        for i in range(1, n + 1):
            up[i][j] = up[up[i][j - 1]][j - 1]

    def jump(u, k):
        bit = 0
        while k:
            if k & 1:
                u = up[u][bit]
            k >>= 1
            bit += 1
        return u

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a

        a = jump(a, depth[a] - depth[b])

        if a == b:
            return a

        for j in range(LOG - 1, -1, -1):
            if up[a][j] != up[b][j]:
                a = up[a][j]
                b = up[b][j]

        return up[a][0]

    q = int(input())
    ans = []

    for _ in range(q):
        a, b, c = map(int, input().split())

        l = lca(a, b)
        dist = depth[a] + depth[b] - 2 * depth[l]

        if c >= dist:
            ans.append(str(b))
            continue

        up_from_a = depth[a] - depth[l]

        if c <= up_from_a:
            ans.append(str(jump(a, c)))
        else:
            remaining = c - up_from_a
            down_from_l = depth[b] - depth[l]
            ans.append(str(jump(b, down_from_l - remaining)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```预处理部分构建一次有根树信息。 迭代 DFS 避免了链形树上的递归深度问题，其中递归 DFS 可能会超出 Python 的递归限制。 

这`jump`核心函数是二进制提升操作。 它读取的位`k`并应用祖先表中相应的 2 的幂。 这些跳跃的顺序并不重要，因为每次跳跃都沿着相同的路径向上移动。 

这`lca`函数首先对齐两个节点的深度。 之后，它将两个节点一起从 2 的大幂降到小幂，直到它们的父节点匹配。 返回的父母是最低的共同祖先。 

查询逻辑完全遵循四个算法步骤。 唯一微妙的部分是道路的后半部分。 当到达LCA后继续运动时，直接向下跳是不可能的，所以代码反转视角，从`b`。 

Python 整数可以安全地处理所有距离，但主要关注的是避免查询中不必要的工作。 每个查询仅执行恒定数量的二进制提升操作。

 ## 边缘情况

 对于第一种边缘情况，仍然必须处理从向下开始的路径。 在：```
3
1 2
2 3
1
1 3 1
```的生命周期评估`1`和`3`是`1`。 路径的第一部分长度为零，因此算法进入第二种情况并从节点向上跳转`3`比剩余的向下距离少一。 它返回节点`2`。 

对于能量大于路径长度的情况：```
3
1 2
2 3
1
1 3 10
```距离只有两条边。 算法立即返回`b`，防止任何超出目的地的无效跳转。 

对于两个节点相等的情况：```
1
1
1 1 10
```LCA 是节点本身，距离为零。 查询在尝试任何提升之前完成，返回节点`1`。
