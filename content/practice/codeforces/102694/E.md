 ## 解决方案
 ## 问题理解

 我们有一棵有根树，其根是节点`1`。 每个节点存储正整数金额。 子树产生的值是该子树内每个节点中存储的值的乘积。 

两个操作必须在线处理。 更新替换一个节点的值。 查询要求两个子树的值之间的比率。 由于产品可能变得巨大，比率大于或等于`10^9`必须准确打印`1000000000`。 

困难在于，更改一个节点会影响包含该节点的每个子树，即它的所有祖先。 直接模拟会反复向上穿过树，这太慢了。 

限制允许周围`O((n+q) log n)`运营。 高达`3 * 10^5`节点和查询，任何扫描整个子树或每个操作的整个根到节点路径的任何操作都可以大致达到`9 * 10^10`操作并且不会完成。 

主要的边缘情况是由大型产品和树结构引起的。 单节点树是有效的：```
Input
1
1
1 1 1
```唯一可能的子树是根，所以答案是：```
1.0000000000
```使用普通乘法的粗心实现即使在中等输入下也会溢出，而正确的解决方案只需要对数。 

另一种情况是节点更新多次时：```
Input
2
1 2
3
1 2 10
1 2 100
2 2 1
```最终比例为`100`，因为旧值必须被替换，而不是相乘。 忘记删除之前的贡献会产生错误的答案。 

第三种边缘情况是分母子树较大时：```
Input
3
1 2
1 3
2
1 2 5
2 1 2
```子树的值`1`是`5`，而子树`2`是`5`，所以答案是`1`。 仅比较祖先或深度的解决方案将会失败，因为子树值取决于所有后代。 

## 方法

 最简单的方法是维护每个节点值并在需要时计算子树乘积。 对于节点上的查询`x`，我们可以遍历整个子树`x`，将所有值相乘，然后重复`y`。 这是正确的，因为子树值的定义正是该乘积。 

当树变大时，问题就会出现。 一棵星形树，`n = 300000`有一个子树，几乎包含每个节点。 一个查询可能需要数十万次乘法，而对数十万个查询执行此操作会达到大约`9 * 10^10`运营。 

第一个观察结果是乘积很难维护，但对数可以将它们转化为总和：$$\log(a \times b)=\log(a)+\log(b)$$我们不存储子树乘积，而是存储每个子树内的对数和。 两个子树值的比率成为两个和的差。 

剩下的挑战是更新。 如果节点`x`以对数差异变化`d`，每个祖先子树总和必须改变`d`。 这正是从根到的树路径更新`x`，然后是询问与节点关联的值的查询。 

欧拉之旅给出了有益的转变。 如果我们在节点存储一个值并在其欧拉区间查询总和，我们将获得子树总和。 使用具有差分技术的 Fenwick 树，根到节点的贡献可以表示为欧拉阶上的范围更新，从而允许每个操作以对数时间运行。 

最后一种方法保留每个节点的对数贡献，并使用欧拉排序和 Fenwick 树来维护子树和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 最坏情况下每次查询/更新 O(n) | O(n) | 太慢了 |
 | 最佳 | 每次操作 O(log n) | O(n) | 已接受 |

 ## 算法演练

 1. 从根运行 DFS 并计算`tin[x]`和`tout[x]`对于每个节点。 的子树`x`成为连续欧拉线段`[tin[x], tout[x]]`。 
2. 存储每个节点的对数值。 最初每个节点包含`1`，所以每个对数都是`0`。 
3. 当节点值发生变化时`old`到`new`，计算：$$\Delta=\log(new)-\log(old)$$这是包含该节点的每个子树必须获得的数量。 

1.添加`\Delta`到节点的欧拉位置，并在子树区间结束后使用芬威克树减去它。 这使得查询子树等于对其欧拉区间求和。 
2. 对于请求节点的查询`x`和`y`, 获取对数子树和`sx`和`sy`。 所需的比率是：$$e^{sx-sy}$$如果差异足够大，结果达到`10^9`，立即打印瓶盖。 

工作原理：Fenwick 树准确存储每个更新节点对包含该节点的所有子树的累积对数贡献。 每个节点的值精确地贡献于所有祖先的欧拉间隔，因此子树的维护总和始终等于其真实乘积的对数。 取两个维护和的差值给出所请求比率的对数，其在求幂后恢复答案。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0.0] * (n + 3)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        res = 0.0
        while i:
            res += self.bit[i]
            i -= i & -i
        return res

    def range_add(self, l, r, v):
        self.add(l, v)
        if r + 1 <= self.n:
            self.add(r + 1, -v)

def solve():
    n = int(input())
    graph = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        a, b = map(int, input().split())
        graph[a].append(b)
        graph[b].append(a)

    tin = [0] * (n + 1)
    tout = [0] * (n + 1)
    order = 0

    sys.setrecursionlimit(1000000)

    def dfs(v, p):
        nonlocal order
        order += 1
        tin[v] = order
        for u in graph[v]:
            if u != p:
                dfs(u, v)
        tout[v] = order

    dfs(1, 0)

    bit = Fenwick(n)
    values = [1] * (n + 1)
    logs = [0.0] * (n + 1)

    q = int(input())
    ans = []

    for _ in range(q):
        t, x, y = map(int, input().split())

        if t == 1:
            delta = math.log(y) - logs[x]
            logs[x] = math.log(y)
            values[x] = y
            bit.range_add(tin[x], tout[x], delta)
        else:
            diff = bit.sum(tout[x]) - bit.sum(tin[x] - 1)
            diff -= bit.sum(tout[y]) - bit.sum(tin[y] - 1)

            if diff >= math.log(1e9):
                ans.append("1000000000")
            else:
                ans.append("{:.10f}".format(math.exp(diff)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```DFS为每个子树分配一个连续的区间。 Fenwick 树不直接存储子树总和。 它存储欧拉位置上的差异数组，因此向子树区间添加贡献就是一对点更新。 

更新操作保持`logs[x]`作为节点值的当前对数。 新旧对数之间的差异正是所有祖先子树总和需要改变的量。 

查询通过获取前缀和来重建子树和`tout[x]`减去之前的前缀和`tin[x]`。 将两个对数子树和相减即可得到所请求比率的对数。 

在调用之前执行上限检查`exp`。 这可以避免溢出，因为实际的产品比例可能会很大。

 ## 边缘情况

 对于单节点树，DFS 创建长度为 1 的欧拉区间。 芬威克树没有更新，每个查询都比较相同的单个值，产生`1`。 

对于重复更新，存储的对数将被覆盖而不是累积。 例如，将节点从`4`到`5`添加`log(5)-log(4)`， 不是`log(5)`。 这使维护的子树值保持一致。 

对于非常大的答案，该算法在求幂之前比较对数。 如果差异至少为`log(10^9)`，不需要精确的值，因为所需的输出已经固定为`1000000000`。
