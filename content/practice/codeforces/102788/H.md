 ## 解决方案
 ## 问题理解

 我们有一台以值 1 开头的机器。该机器的程序是一系列命令。 第一个命令将当前值增加 1，另一个命令将其增加一个大于 1 的未知值 x，第三个命令将当前值乘以 7。 

对于固定的 x，Vasily 计算有多少个不同的命令序列恰好在 N 处完成。我们给定 N 和所需的计数 K，我们必须找到使有效程序的数量等于 K 的最小 x。如果不存在这样的 x，我们输出 0。 

N 上的约束足够小，可以采用二次方法。 由于 N 最多为 10000，因此执行大约 10^8 个简单操作的解决方案接近 Python 中的实际极限，但探索指数级许多命令序列的解决方案是不可能的。 K 值可以大到 2^60，因此我们永远不需要高于该点的精确计数。 我们只需要知道答案是否达到或超过 K，这使我们能够限制中间值并避免不必要的大整数增长。 

主要边缘情况来自接近极限的 x 值。 如果 x 大于 N，则永远不能使用命令 2，但答案必须满足 x < N。例如，如果 N = 3 并且 K = 1，则唯一有效的程序是 1,1，因此没有有效的 x，输出为 0。 

另一种情况是乘法创建额外的路径。 对于 N = 7 且 x = 5，有效程序为 1,1,1,1,1,1, 2,1, 1,2 和 3，得出 K = 4。仅考虑加法的解决方案将计算三个程序并失败，因为它忽略了乘法转换。 

最后的边缘情况是计算期间计数大于 K 时。 例如，如果候选 x 产生超过 2^60 个可能的程序，则无需存储精确值。 粗心的实现可能会花费时间构建巨大的整数，而不是在所需的阈值处停止。 

## 方法

 直接的暴力解决方案将生成所有可能的命令序列并对其进行模拟，直到达到 N。这是正确的，因为每个程序都对应于一个操作序列。 问题是序列的数量增长得非常快。 即使在考虑乘法之前，使用加法编写差异的方法数量也会以组合方式增长，因此枚举程序变得不可能。 

更好的观点是计算实现每个值的方法，而不是构建程序。 对于固定的 x，令 dp[v] 为将初始值 1 转换为值 v 的命令序列的数量。以 v 结尾的程序的最后一个命令必定是三种可能性之一。 它可以加 1，意味着我们来自 v - 1。它可以加 x，意味着我们来自 v - x。 或者它可以乘以 7，这意味着如果 v 可被 7 整除，则我们来自 v / 7。 

其递归式为：

 dp[v] = dp[v - 1] + dp[v - x] + dp[v / 7]

 其中仅包含有效的转换。 计算 1 x 的递推式需要 O(N)。 由于我们需要最小的 x，因此我们只需尝试从 2 到 N - 1 的 x，并在第一个产生 K 的地方停止。 

重要的观察是 x 的搜索空间足够小。 我们不需要更复杂的数学反演，因为 N 只有 10000。

 ## 算法演练

1. 尝试从 2 到 N - 1 的每个可能的 x 值。我们按升序测试值，因为所需的答案是最小的有效 x。 
2. 对于当前的x，创建一个动态编程数组，其中dp[i]表示从起始值1到值i的程序数量。 
3. 初始化dp[1] = 1，因为在执行任何命令之前，我们已经处于起始状态。 
4. 处理从 2 到 N 的值。添加每个可能的先前状态的路数：
 当 i >= x + 1 时，命令 1 为 dp[i - 1]；当 i >= x + 1 时，命令 2 为 dp[i - x]；当 i 可被 7 整除时，命令 3 为 dp[i / 7]。 
5. 计算出dp[N]后，与K进行比较，如果相等，则输出当前的x。 
6. 如果所有可能的 x 都已测试但没有一个有效，则输出 0。 

为什么它有效：

 每个以 i 值结尾的程序都有一个唯一的最后一个命令。 删除最后一个命令会留下一个较小的有效程序，恰好以最后一个操作之前的状态结束。 递归计算所有可能的先前状态，并且这些组不能重叠，因为最后一个命令不同。 因此 dp[i] 对每个有效程序只计数一次。 按升序测试 x 可保证第一个匹配是最小的可能值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

LIMIT = 1 << 60

def count_programs(n, x, target):
    dp = [0] * (n + 1)
    dp[1] = 1

    for i in range(2, n + 1):
        cur = dp[i - 1]

        if i - x >= 1:
            cur += dp[i - x]

        if i % 7 == 0:
            cur += dp[i // 7]

        if cur > target:
            cur = target + 1

        dp[i] = cur

    return dp[n]

def solve():
    n, k = map(int, input().split())

    for x in range(2, n):
        if count_programs(n, x, k) == k:
            print(x)
            return

    print(0)

solve()
```功能`count_programs`执行演练中描述的动态规划。 该数组的索引与机器显示的实际值相匹配，这避免了程序状态和数组位置之间的转换错误。 

一旦超过 K，计数就会受到限制。只有与 K 相等才重要，因此任何更大的值对于最终决策都是等效的。 这也使中间值易于管理。 

在其他操作之后检查乘法的转换，因为它不依赖于 x。 条件`i % 7 == 0`是必要的，因为通过将先前的值乘以 7 只能产生可被 7 整除的数字。

对于第二个样本，N = 14，K = 3。 

测试低于 14 的每个 x 都会得到与 3 不同的计数。动态编程过程会检查每个可能的转换，包括从 2 到 14 的乘法，但没有 x 会创建正好三个程序，因此输出为 0。

 ## 边缘情况

 对于 N = 3 和 K = 1，每个可能的 x 都是无效的，因为 x 必须在 2 和 N - 1 之间，唯一的候选者是 x = 2。 x = 2 的动态规划计数大于 1，因为两种加法都可以使用，因此算法正确地拒绝它并打印 0。 

对于 N = 7 和 K = 4，算法在处理值 7 时达到乘法转换。它包括 dp[1]，因为 7 可被 7 整除，添加仅包含命令 3 的程序。这是仅模型加法的方法所错过的转换。 

对于程序数量巨大的情况，K + 1 的上限可以防止固定整数大小的语言因溢出而导致的错误比较，并避免浪费时间存储不影响答案的值。
