 ## 解决方案
 ## 问题理解

 该问题给出了几个团队在执行经典的三杆河内塔解决方案时的中间位置。 每个团队都遵循完全相同的递归过程，移动所有`N`杆上的圆盘`A`到杆`B`。 对于每个团队，我们都会得到一个长度的字符串`N`，其中字符位于位置`i`描述当前的磁盘棒`i`, 带磁盘`1`是最小的和磁盘`N`是最大的。 任务是确定哪个团队在此过程中走得最远，这意味着记录的配置在唯一的最佳序列中显示得最晚的团队。 如果多个团队具有相同的配置，则必须选择其中的第一个团队。 

磁盘数量可达`1000`，并且团队数量也可以达到`1000`。 总移动次数为`2^N - 1`，因此即使对于中等较小的序列，存储或模拟整个序列也是不可能的`N`。 直接模拟已经变得毫无用处`N = 60`，因为移动次数超出了正常时间限制内可以处理的数量。 该解决方案必须大致有效`O(NM)`时间，因为输入本身包含`NM`人物。 

第一个棘手的情况是移动计数不直接存储并且不能适合标准整数类型。 例如，与`N = 1000`，答案可能需要大约一千位。 将配置转换为普通整数的解决方案会溢出或在大量算术上花费不必要的时间。 

另一个边缘情况是当多个团队具有相同的状态时。 例如：```
2 3
AA
BB
BB
```正确的输出是：```
2
```最后两队都完成了拼图，但必须选择最先出现的。 一个粗心的实现更新了答案`>=`而不是仅在`>`会错误地返回团队`3`。 

第二个边缘情况是初始配置：```
3 1
AAA
```正确的输出是：```
1
```第一个状态对应move`0`。 假设至少一个磁盘已移动的实现可能会错误分类此配置。 

## 方法

 最直接的方法是生成河内流程的每个配置，并将每个生成的状态与团队的状态进行比较。 递归过程很容易模拟，因为每个动作都是预先知道的。 问题是序列有`2^N`州。 为了`N = 1000`，这远远超出了任何可能的极限。 即使每纳秒产生一次移动也不会使该方法变得实用。 

关键的观察结果是经典的河内序列具有递归结构。 求解时`N`磁盘来自`A`到`B`，前半部分的动作解决了`N-1`磁盘来自`A`到`C`，然后磁盘`N`移动自`A`到`B`，那么剩下的`N-1`磁盘移动自`C`到`B`。 这意味着最大磁盘的位置立即告诉我们序列的哪一半包含当前状态。 

如果最大的圆盘仍在源棒上，那么答案就在上半部分的某个地方。 如果它在目标杆上，则答案在后半部分，我们只需在交换杆角色的较小磁盘上继续递归即可。 我们不是构建整个序列，而是重建移动数的二进制表示。 每个磁盘贡献一位：该磁盘移动的时刻是否已经发生。 

蛮力方法有效，因为河内序列是确定性的，但会失败，因为序列呈指数增长。 递归结构使我们可以将问题减少到检查每个磁盘一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(2^N)`|`O(N)`| 太慢了 |
 | 最佳 |`O(NM)`|`O(N)`| 已接受 |

 ## 算法演练

 1. 对于每个团队的配置，从最大的圆盘和原始河内参数开始：从杆移动`A`到杆`B`使用杆`C`。 
2、查看当前最大磁盘的位置。 如果仍在源棒上，则移动数属于递归序列的前半部分，因此当前位为`0`。 下一个递归问题是将剩余的圆盘从同一源移动到辅助杆。 
3. 如果最大的圆盘在目标棒上，则移动号码属于后半部分。 当前位是`1`，并且必须在第二个递归阶段考虑剩余的磁盘，从辅助杆移动到目标杆。 
4. 继续，直到处理完所有磁盘。 位序列描述了移动编号。 不要构建大整数，而是从最高有效侧比较这些位串。 
5. 保留具有最大二进制移动表示的团​​队。 仅当找到严格更大的值时才替换当前答案，这会在出现平局时自动保留第一支球队。 

这样做的原因是最大的磁盘在整个最优解决方案期间只改变一次位置。 在此移动之前，每个配置都必须属于第一个递归块。 移动之后，每个配置都属于第二个递归块。 对较小的磁盘重复此参数可以唯一地确定序列中每个状态的位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def get_bits(state):
    n = len(state)
    src, dst, aux = 'A', 'B', 'C'
    bits = []

    for disk in range(n - 1, -1, -1):
        pos = state[disk]
        if pos == src:
            bits.append('0')
            src, dst, aux = src, aux, dst
        else:
            bits.append('1')
            src, dst, aux = aux, dst, src

    return ''.join(bits)

def solve():
    n, m = map(int, input().split())

    best_team = 1
    best = None

    for i in range(1, m + 1):
        state = input().strip()
        value = get_bits(state)

        if best is None or value > best:
            best = value
            best_team = i

    print(best_team)

if __name__ == "__main__":
    solve()
```功能`get_bits`执行递归推理而不使用递归。 循环从最大的磁盘开始，因为它决定了移动数的最高位。 从最大到最小处理磁盘相当于递减递归调用。 

当当前盘在源棒上时，还没有发生移动，所以对应的位为`0`。 较小的磁盘仍处于第一个递归阶段，这会将辅助杆更改为临时目的地。 当圆盘位于目标杆上时，移动已发生，因此该位为`1`，并且棒的角色发生变化以描述第二阶段。 

比较是在字符串上完成的，因为每个状态都会准确地产生`N`位。 等长二进制字符串按字典顺序正确比较，`1`大于`0`，因此不需要大整数转换。

 ## 边缘情况

 对于重复状态的情况：```
2 3
AA
BB
BB
```第一个状态有步数`0`。 两个都`BB`州有移动号码`3`。 该算法为团队生成相同的位串`2`和`3`，并且因为它仅在新值严格更大时更新，所以团队`2`保持选中状态。 

对于初始配置：```
3 1
AAA
```每个磁盘仍然在源棒上。 该算法记录三个零位，代表着步数`0`。 不需要特殊处理，因为即使在任何移动发生之前也适用相同的递归规则。 

对于最大可能的输入，该算法从不构造河内序列。 它只读取每个`1000`每个的字符`1000`团队，因此可能的移动的指数数量永远不会出现在计算中。
