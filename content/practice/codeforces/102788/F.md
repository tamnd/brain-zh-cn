 ## 解决方案
 ## 问题理解

 该任务要求我们重建城市的有向无环图。 城市`m`是所有发货的来源。 对于每个城市`i`，我们得到`D[i]`，起始于的不同有向路径的数量`m`并结束于`i`。 我们必须输出任何一组能够精确创建这些路径计数的有向道路。 该图必须保持非循环，并且不能包含同一对城市之间的多条道路。 原始声明将此描述为根据收集的路线计数构建可能的货运地图。 

关键的观察是，一个城市的路线数量完全由其进入的道路决定。 来自城市的每条传入道路`u`贡献所有已经到达的路径`u`，所以如果一个城市有即将到来的邻居`p1, p2, ...`，其值必须满足：`D[v] = D[p1] + D[p2] + ...`由于该图是非循环的，因此城市的每个父级都必须具有较小的路径数。 值为零的城市无法从源头到达，并且应该没有传入道路。 源城市本身恰好有一条通往自身的路径，即空路，因此其值必定为一。 

极限`n <= 60`很小，但值`D`可以大到`2^62`，因此依赖于值的数字大小的算法是不可能的。 我们无法扩展计数、枚举路径或对值使用动态规划。 构建必须使用图表的结构以及只有六十个城市的事实。 

重要的边缘情况是值为零的城市、值一的城市和重复值。 零价值城市绝不能意外地获得优势。 例如：```
n = 3, m = 1
D = [1, 0, 0]
```正确的图没有路。 添加一条来自城市的道路`1`到城市`2`将立即创建一条路径并使`D[2]`不正确。 

重复的值需要小心处理。 例如：```
n = 4, m = 1
D = [1, 1, 1, 3]
```最后一个城市除了直接源头贡献外，还需要两条源头路径。 将两个价值一的城市连接到它提供了三种路径。 将相等的值视为可互换而不考虑构造顺序可能会产生循环或无效的父级选择。 

## 方法

 直接方法将尝试独立决定每个城市的传入道路。 对于一个有价值的城市`x`，我们将在所有先前的城市中搜索并找到一个子集，其路径计数总和为`x`。 这是正确的，因为进入节点的路径数恰好是其父节点路径数的总和。 然而，尝试所有子集需要指数时间。 有六十个城市，最坏的情况需要考虑`2^60`可能性，远远超出了极限。 

有用的观察是我们不需要解决一般的子集和问题。 给定的路径计数来自 DAG，这意味着每个值都可以分解为早期城市的值。 如果我们按照路径计数的递增顺序处理城市，则每个可以作为父级的城市都已被处理。 我们可以贪婪地取最大的可用较小值，直到达到所需的总和。 

对于有效输入，这种贪婪分解是有效的，因为如果剩余量无法被最大的可用较小值覆盖，那么以后的较小值也无济于事。 排序顺序保留了每个缺失部分必须出现在当前城市之前的属性。

 ## 算法演练

 1. 检查源城市，收集所有路径数为正的城市。 值为零的城市将被忽略，因为它们必须保持无法到达。 
2. 按路径数对正值城市进行排序。 将它们从小值处理到大值可以保证当我们建造城市时，所有可能的父母都已经可用。 
3. 对于除源城市之外的每个城市，查找其路径计数总计达到其所需值的先前城市。 将这些父城市的有向边添加到当前城市。 
4. 要找到父母，请从最大路径计数向下扫描以前的城市。 当城市值不超过剩余金额时，将其用作父级并从剩余金额中减去它。 
5.输出所有收集到的道路。 

不变的是，在处理已排序城市的任何前缀之后，每个处理的城市已经具有其所需数量的来自源的路径。 当添加一个新城市时，其传入边缘恰好贡献了所选的先前路径计数，因此新城市的值也是正确的。 由于所有边都从较小的值到较大的值，因此不会出现循环。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    d = list(map(int, input().split()))

    src = m - 1
    nodes = [(d[i], i) for i in range(n) if d[i] > 0]
    nodes.sort()

    pos = {}
    for idx, (_, v) in enumerate(nodes):
        pos[v] = idx

    edges = []

    for idx, (val, v) in enumerate(nodes):
        if v == src:
            continue

        need = val
        for j in range(idx - 1, -1, -1):
            if nodes[j][0] <= need:
                edges.append((nodes[j][1] + 1, v + 1))
                need -= nodes[j][0]
            if need == 0:
                break

    print(len(edges))
    for a, b in edges:
        print(a, b)

if __name__ == "__main__":
    solve()
```该代码首先排除了无法到达的城市。 它们无法对任何路由计数做出贡献，因为它们没有来自源的路径。 

排序列表存储路径计数和城市索引对。 该列表上的循环是算法的构造顺序。 对于一个有需求价值的城市`val`，变量`need`跟踪仍有多少条路径需要创建。 每个选定的父级都会贡献其全部路径数，因此减去该值恰好反映了路径计数方程。 

源城市被跳过，因为它的值已经由空路径定义。 边缘方向始终从较早排序的城市到较晚排序的城市，这可以防止循环。 Python 整数处理`2^62`直接范围，因此不需要溢出处理。

## 边缘情况

 对于无法到达的城市，算法永远不会将它们放入已排序的肯定列表中。 为了：```
3 1
1 0 0
```除源之外，不会处理任何城市，因此输出包含零条道路，并且路径计数保持正确。 

对于源的多个直接子级：```
4 1
1 1 1 3
```两个一值城市都是在三值城市建成之前就可以使用的。 该算法将它们与源贡献一起使用来创建所需的三个路由。 

对于重复的较大值：```
5 1
1 1 1 2 4
```价值二的城市是由两个价值一的城市创建的，价值四的城市可以使用较小的已建成的城市。 按升序处理可确保每个可能的父级在需要之前都可用。
