 ## 解决方案
 ## 问题理解

 任务并不是要求我们构建整个幻方。 我们只需要第一行中的数字之和。 一个正常大小的幻方`n`包含来自的每个整数`1`到`n²`恰好一次，并且每一行都有相同的总和。 输入给出正方形的边长，输出必须是公共行总和。 

尺寸可以大到`1000`，所以模拟正方形是不必要的。 即使是简单的构造，在最大的情况下也需要存储一百万个单元，而所需的答案仅取决于幻方的数学属性。 预期的解决方案应该在恒定的时间内运行，因为任何处理所有数据的方法`n²`细胞正在做问题不需要的工作。 

不寻常的情况是小订单。 为了`n = 1`，唯一的单元格包含`1`，所以答案是`1`。 假设每个方格都有多行的解决方案在这里可能会失败。 例如，输入`1`必须产生输出`1`。 

价值`n = 2`被该语句排除，因为不存在该尺寸的普通幻方。 程序不应该尝试构建一个或依赖于这种情况的构建公式。 法官不会提供此意见。 

## 方法

 直接的方法是生成一个幻方并添加其第一行的元素。 这是有效的，因为每个有效的构造都将包含正确的第一行，并且行总和将与所需的答案相匹配。 然而，建造广场是没有必要的。 为了`n = 1000`， 有`1,000,000`单元格，因此即使是简单的遍历也已经执行了一百万次操作并使用大量内存。 更复杂的结构会增加额外的开销，但无法帮助我们找到所请求的值。 

关键的观察是每个数字`1`到`n²`恰好出现一次。 所有单元格的总和是第一个单元格的总和`n²`正整数：$$\frac{n^2(n^2+1)}{2}$$幻方有`n`总和相同的行。 将总和除以行数得出一行的总和：$$\frac{n^2(n^2+1)}{2n}$$简化为：$$\frac{n(n^2+1)}{2}$$第一行必须具有此值，因为所有行共享相同的总和。 整个问题被简化为评估这个公式。

 | 蛮力 | O(n²) | O(n²) | 太慢而且没必要 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读订单`n`的魔方。 的价值`n`是足够的信息，因为行总和完全由平方大小决定。 
2. 使用公式计算幻和`n * (n * n + 1) // 2`。 该表达式来自所有单元格的总值除以行数。 
3. 打印计算值。 

为什么它有效：

 正方形内的数字恰好是来自的整数`1`到`n²`，所以它们的总和是固定的。 由于每行的总和相同，因此总和必须平均分配`n`行。 该公式直接计算单行值，这意味着它也必须是第一行的总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    print(n * (n * n + 1) // 2)

if __name__ == "__main__":
    solve()
```程序读取唯一的输入值并立即应用导出的公式。 乘法`n * n`是安全的，因为最大可能值只有一百万。 Python 整数还消除了对溢出的任何担忧。 

除法是用整数除法进行的，因为最终结果始终是整数。 表达式排列为`n * (n * n + 1) // 2`，这使计算保持简单，同时保持精确的算术。

 ## 边缘情况

 对于`n = 1`，公式给出：$$1 \times (1^2 + 1) / 2 = 1$$算法打印`1`，匹配正方形中唯一的单元格。 从多行假设开始的基于构造的解决方案可能会错误地失败。 

为了`n = 3`，公式给出：$$3 \times (9 + 1) / 2 = 15$$粗心的解决方案可能会尝试从一个特定的幻方布局中得出答案。 这适用于这种情况，但它无法解释为什么每个有效方块具有相同的第一行总和。 该公式使用所有幻方共享的不变量，因此无论排列如何它都有效。 

为了`n = 1000`，公式给出：$$1000 \times (1000000 + 1) / 2 = 500000500$$该算法执行与以下相同的少量操作`n = 1`，避免了模拟方法所需的百万单元处理。
