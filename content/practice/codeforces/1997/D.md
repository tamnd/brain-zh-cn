[CF 1997D - 最大化根](https://codeforces.com/problemset/problem/1997/D)

 **评分：** 1500
 **标签：** 二分查找、dfs 和类似、dp、贪婪、树
 **求解时间：** 2m 36s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们得到了一棵有根的树。 每个顶点都包含一个非负数。 

操作可以应用于任何非叶顶点。 当我们选择一个顶点时$v$，我们增加值$v$的子树中的每个其他顶点同时减少 1$v$一个。 操作后所有值必须保持非负值。 

目标是在执行任意数量的有效操作后最大化根的价值。 

该树最多包含$2 \cdot 10^5$所有测试用例的顶点。 值可以大到$10^9$。 直接模拟操作的解决方案是不可能的，因为操作数量也可能非常大。 即使是单个顶点也可能增加数十亿倍。 

总量约束$n$立即表明我们需要接近的东西$O(n)$或者$O(n \log n)$每个测试文件。 任何重复修改子树或搜索操作的方法都会太慢。 

该问题最危险的部分是操作在树的不同级别之间交互。 

考虑：```
1(0)
|
2(10)
|
3(0)
```一个天真的想法是顶点 2 可以向上捐赠所有 10 个单位。 那是错误的。 顶点 2 上的每个操作也会减少顶点 3 的值。 由于顶点 3 从零开始，因此顶点 2 甚至无法执行一项操作。 

The correct answer is 0, not 10.

 另一个微妙的情况是：```
1(0)
|
2(5)
|
3(3)
```顶点 2 最多可以执行三个操作，因为顶点 3 是瓶颈。 之后，顶点2变为8，顶点3变为0。现在顶点2不能再操作。 

如果粗心的解决方案仅查看子树内的总和，则会错误地得出所有八个单元最终都能到达根的结论。 

第三个重要的例子是叶子。```
1(0)
|
2(7)
```由于顶点 2 没有子节点，因此它无法执行操作。 根最多可以从顶点 2 接收 7 个单元，并且子树内部不可能进行任何转换。 叶子的行为与内部顶点不同，必须单独处理。 

## 方法

 蛮力解释很简单。 重复搜索有效的操作，应用它，更新所有受影响的顶点，并继续，直到没有操作可以改善根。 

这是正确的，因为它完全遵循定义。 不幸的是，它的速度慢得令人绝望。 单个操作可能会触及整个子树，从而导致$O(n)$。 更糟糕的是，操作数量可能多达$10^9$。 即使对于小树来说，这也是不可行的。 

为了更快地获得某些东西，我们需要停止考虑单个操作，而是提出一个可行性问题。 

假设我们希望根至少以 value 结尾$X$。 

我们可以确定这是否可能吗？ 

如果我们能够有效地回答这个问题，那么通过二分查找就可以找到最终的答案。 

关键的观察是，运营只会向上移动资源。 每个子树必须能够为其父树提供足够的价值。 这表明了自下而上的 DFS。 

考虑一个节点$v$并假设其父级需要从中获取一些金额。 

如果$v$是一片叶子，它能提供的最大量就是$a_v$。 

对于内部节点，事情变得更有趣。 

认为$v$必须至少以$need$其父级可用的单位。 

如果$a_v \ge need$， 然后$v$已经满足要求了。 任何额外的价值都是无害的。 

如果$a_v < need$， 然后$v$必须以某种方式创造$need-a_v$额外的单位。 唯一的方法是执行操作$v$。 

每次操作都会增加$v$增加 1，但每个子子树消耗 1 个单位。 从而创造出$d$额外单位$v$要求每个子子树至少提供$d$单位。 

这会导致非常干净的复发。 

让$req(v)$表示每个孩子必须能够提供的最小值。 

如果$a_v \ge req(v)$，孩子只需要满足$req(v)$。 

如果$a_v < req(v)$，赤字为$req(v)-a_v$。 产生这种赤字需要子级满足最终需求和消耗的资源：$$req(child)=req(v)+(req(v)-a_v)$$

$$=2 \cdot req(v)-a_v$$整个问题变成了从根向下传播到叶子的可行性检查。 

蛮力之所以有效，是因为操作向上转移资源。 递归之所以有效，是因为它准确地捕获了子树必须保证支持其父级目标值的资源量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 无限的、潜在的数十亿次操作 | O(n) | 太慢了 |
 | 最佳 | O(n log A) | O(n log A) | O(n) | 已接受 |

 这里$A$是答案范围，大约可达$10^9$。 

## 算法演练

 ### 可行性检查

 假设我们想知道根是否可以达到值$X$。 

根最初包含$a_1$。 树的其余部分必须提供$$need = X-a_1$$额外的单位。 

如果$need \le 0$，目标已经达到了。 

否则，我们递归地验证每个子树是否可以支持所需的数量。 

### 递归含义

 对于一个节点$v$，定义一个DFS参数$need$。 

其含义是：

 > 子树$v$必须能够至少交付$need$单位到其父级。 

### 内部节点转换

 1.如果$v$是一片叶子，返回是否$a_v \ge need$。 
2.如果$a_v \ge need$， 然后$v$已经包含了足够的价值。 

每个孩子只需要满足相同的要求$need$。 
3.如果$a_v < need$， 让$$d = need-a_v$$成为赤字。 

节点$v$必须生成$d$通过以下行动增加单位：$v$。 
4. 每个这样的单元花费每个子子树一个单元。 

因此，每个孩子必须提供$$need+d =2\cdot need-a_v$$单位。 
5. 递归地验证每个子项是否符合新要求。 

### 二分查找

 1. 设搜索范围为$[a_1, 10^{18}]$。 
2. 对于中点$mid$，运行可行性DFS。 
3. 如果可行，将下限向上移动。 
4. 否则将上限向下移动。 
5. 最大的可行值就是答案。 

### 为什么它有效

 DFS 不变量是：

 > 当使用参数检查节点时$need$，递归确定该子树是否至少可以保证$need$在任何必要的内部操作之后，节点本身的单元。 

对于叶子来说，这是立即的，因为没有可用的操作。 

对于内部节点，如果其自身值已经满足要求，则子节点不需要补偿。 如果达不到$d$， 确切地$d$该节点的操作是必要的。 每个这样的操作都会消耗每个子子树的一个单元，因此每个子树必须支持一个额外的单元$d$单位。 重复是必要的也是充分的。 

由于可行性谓词是单调的，如果一个值$X$是可以实现的，那么每个更小的值也是可以实现的。 二分查找有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 20)

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        children = [[] for _ in range(n)]

        parents = list(map(int, input().split()))
        for v in range(1, n):
            p = parents[v - 1] - 1
            children[p].append(v)

        def feasible(target):
            need_root = target - a[0]
            if need_root <= 0:
                return True

            INF = 10**18

            def dfs(v, need):
                if need > INF:
                    return False

                if not children[v]:
                    return a[v] >= need

                if a[v] >= need:
                    child_need = need
                else:
                    child_need = 2 * need - a[v]
                    if child_need > INF:
                        return False

                for to in children[v]:
                    if not dfs(to, child_need):
                        return False

                return True

            for to in children[0]:
                if not dfs(to, need_root):
                    return False

            return True

        lo = a[0]
        hi = 10**18

        while lo < hi:
            mid = (lo + hi + 1) // 2

            if feasible(mid):
                lo = mid
            else:
                hi = mid - 1

        print(lo)

solve()
```该树被存储为子邻接列表，因为每次 DFS 遍历都是从父节点到子节点进行。 

功能`feasible(target)`检查根是否可以提升到`target`。 数量`need_root`正是必须从根的子节点到达的数量。 

DFS 实现了上面导出的递归。 叶子是基本情况。 内部节点要么已经满足要求，要么必须通过消耗所有子子树的资源来补偿不足。 

溢出保护使用`INF`很重要。 沿着长链，重复次数可能会反复使所需值加倍。 真正的答案永远不会超出所选的二分搜索范围，因此上述任何要求`10^18`可以安全地视为不可能。 

二分查找使用标准上中点公式`(lo + hi + 1) // 2`以避免无限循环。

    sys.setrecursionlimit(1 << 20)

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        children = [[] for _ in range(n)]

        p = list(map(int, input().split()))
        for v in range(1, n):
            children[p[v - 1] - 1].append(v)

            need = target - a[0]
            if need <= 0:
                return True

            def dfs(v, req):

                    return a[v] >= req

                child_req = req if a[v] >= req else 2 * req - a[v]

                lo = mid
            else:
                hi = mid - 1

        out.append(str(lo))

    return "\n".join(out) + "\n"

 ## 边缘情况

 ### 深瓶颈叶

 输入：```
1
3
0 10 0
1 2
```树：```
1(0)
|
2(10)
|
3(0)
```为了使根等于1，节点2必须提供1个单位。 由于节点 2 已经拥有足够的价值，因此 DFS 也向节点 3 请求 1 个单元。 节点 3 是值为 0 的叶子，因此检查失败。 

该算法输出 0。这与实际过程匹配，因为节点 2 上的每个操作都会将节点 3 降低到零以下。 

### 内部节点赤字放大

 输入：```
1
3
0 1 10
1 2
```树：```
1(0)
|
2(1)
|
3(10)
```试图使根等于 6 需要节点 2 提供 6 个单位。 

节点 2 仅包含 1 个单位，因此赤字为 5。 

孩子的要求变成：$$2 \cdot 6 - 1 = 11$$叶子 3 只有 10 个单元，因此目标失败。 

递归正确地捕捉到了这样一个事实：在节点 2 生成额外价值会消耗节点 3 的资源。 

### 根的叶子孩子

 输入：```
1
2
0 7
1
```根只能接收顶点 2 已经存在的资源。由于顶点 2 是叶子，因此它无法通过操作创造额外的价值。 

DFS 只是检查叶子是否有足够的价值。 最大根值变为$0 + 7 = 7$，这正是正确的答案。
