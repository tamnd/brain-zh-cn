 ## 解决方案
 ## 问题理解

 我们得到了一个偶数长度的括号序列，但是奇数位置的每个字符都被删除了。 仅保留位置 2、4、6... 处的括号。 

保证原始序列是正则括号序列（RBS），并且总是至少有一个有效的恢复。 我们可以将奇数位置的每个下划线替换为`(`或者`)`。 

对于任何已完成的 RBS，其成本定义为匹配的括号对之间的距离之和。 如果左括号位于位置`l`与位置处的右括号匹配`r`，该对贡献`r - l`到总成本。 

在所有有效的修复体中，我们必须找到可能的最小成本。 

单个测试用例的长度可以达到`2 · 10^5`，所有测试用例的总长度也最多为`2 · 10^5`。 任何检查所有修复体的解决方案都是不可能的，因为`2^(n/2)`填补缺失职位的方法。 甚至一个`O(n²)`算法在上限时会太昂贵。 每个测试用例我们都需要一些线性或接近线性的东西。 

问题的一个微妙部分是，最小化成本并不等同于仅仅构建任何有效的 RBS。 不同的有效修复体可以产生不同的匹配结构。 

考虑：```
n = 4
_(_)
```修复`(())`有成本`3 + 1 = 4`。 

如果我们试图在不尊重有效性的情况下贪婪地创建对，我们可能会错误地认为`()()`是可能的，但需要付出代价`2`，但固定的偶数位置阻止了这种恢复。 

另一个容易犯的错误是在构建序列后显式计算匹配对。 这是有效的，但对成本有一个更简单的观察，可以直接得出答案。 

例如：```
_)_)_)_)
```唯一有效的恢复是：```
()()()()
```成本是`1 + 1 + 1 + 1 = 4`。 

产生不必要嵌套的重建策略会增加成本并产生错误的答案。 

## 方法

 蛮力的想法很简单。 对于每个奇数位置，尝试两种可能的括号，生成所有修复体，仅保留常规括号序列，计算其成本，并取最小值。 

这是有效的，因为它直接检查每个可行的答案。 问题在于修复的数量。 有`n/2`删除了位置，所以搜索空间是`2^(n/2)`。 和`n = 200000`，这是一个天文数字。 

为了更快地获得某些东西，我们需要了解成本的真正衡量标准。 

假设左括号位于位置`l`与位置处的右括号匹配`r`。 其贡献是：```
r - l
```对所有匹配对求和得出：```
(sum of closing positions) - (sum of opening positions)
```每个位置都属于一对匹配的，无论是作为左括号还是作为右括号。 因此，一旦我们知道哪些位置包含左括号，成本就完全确定了。 

那么问题就变成了：

 > 构造一个有效的括号序列，其开仓位置之和尽可能大。 

为什么最大？ 因为：```
cost = constant - 2 * (sum of opening positions)
```所有位置的总和是固定的，因此最小化成本相当于最大化左括号占用的位置总和。 

现在从左到右看一下序列。 

在每个奇怪的位置我们选择一个括号。 

如果当前余额为零，我们被迫放置`(`。 配售`)`会立即使前缀无效。 

如果余额为正，则放置`)`总是比放置更好`(`因为它使开口尽可能远离右侧。 由于奇数位置是从左到右处理的，因此使用`)`只要允许，就会推迟未来对较大指数的开仓，从而增加开仓总和。 

这产生了一个非常简单的贪心构造：

 如果余额为零，则输入`(`。 

否则，将`)`。 

偶数位置固定并正常处理。 

构造出最优序列后，我们仍然需要最小成本。 我们可以计算它而无需显式查找匹配对。 

每当我们将左括号放在位置`i`， 添加`i`到一个连续的总和。 

每当我们将右括号放在位置`i`, 减去`i`。 

最终的值正好是：```
(sum closing positions) - (sum opening positions)
```这是所需的成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^(n/2) · n) | O(2^(n/2) · n) | O(n) | 太慢了 |
 | 最优贪心 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化`balance = 0`和`cost = 0`。 
2. 从左到右扫描位置。 
3. 如果位置是奇数，则括号未知。 

如果`balance == 0`， 地方`(`因为任何有效的 RBS 都必须保持每个前缀非负。 

否则放置`)`因为现在使用结束括号会延迟未来开更大头寸的时间，从而最大限度地降低最终成本。 
4. 如果位置为偶数，请使用输入端的固定支架。 
5、确定当前位置的括号后：

 如果是的话`(`， 增加`balance`减一并减去它的位置`cost`。 

如果是的话`)`， 减少`balance`加一并将其位置添加到`cost`。 
6. 继续，直到处理完整个字符串。 
7. 输出`cost`。 

### 为什么它有效

 关键的观察结果是成本等于：```
(sum of closing positions) - (sum of opening positions)
```所有仓位的总和是固定的，因此最小化成本相当于最大化开仓仓位的总和。 

每当当前余额为正时，两者`(`和`)`保持序列可能有效。 选择`)`避免在当前较小的位置创建左括号。 以后需要的任何开括号都会出现在更大的位置，从而增加开仓位置的总和。 

当余额为零时，`)`这是不可能的，因为它会违反 RBS 前缀条件。 因此`(`是被迫的。 

贪心选择在每个奇怪的位置都是局部最优的，并且永远不会降低未来的可行性。 由于每个左括号都被推到有效性允许的最右边，因此所得到的序列最大化了开仓位置的总和，从而最小化了成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        s = input().strip()

        balance = 0
        cost = 0

        for i in range(1, n + 1):
            if i % 2 == 1:
                if balance == 0:
                    ch = '('
                else:
                    ch = ')'
            else:
                ch = s[i - 1]

            if ch == '(':
                balance += 1
                cost -= i
            else:
                balance -= 1
                cost += i

        print(cost)

if __name__ == "__main__":
    solve()
```该算法从不显式重建完整字符串，因为只有当前括号很重要。 

变量`balance`存储通常的括号序列平衡。 基于这种平衡贪婪地选择奇数位置。 

成本计算使用之前导出的身份。 每个开仓头寸都会产生负面影响，而每个平仓头寸都会产生正向影响。 这完全避免了基于堆栈的匹配。 

一个容易出错的细节是索引。 该问题使用从 1 开始的位置，成本公式取决于实际位置数。 循环运行自`1`到`n`，贡献使用`i`直接地。 

另一个微妙之处是，在决定当前的分组后，必须立即更新平衡性。 未来的零头头寸取决于当前余额。
