 ## 解决方案
 ## 问题理解

 我们得到两个独立的序列，它们在许多决策中以乘法和加法相互作用。 每个面包店都有一个位置值$x_i$。 每个邮箱都有一个位置$y_j$以及相关费用$k_j$。 对于每一家面包店，西拉诺都会选择一个邮箱进行访问。 配对面包店的成本$i$有邮箱$j$是两部分的总和： 旅行费用$x_i \cdot y_j$，以及固定的邮箱费用$k_j$。 目标是最小化所有面包店的总成本。 

结构是每一个$x_i$必须与一个邮箱完全匹配，并且选择的成本仅取决于所选邮箱和当前面包店价值。 

限制因素$N, M \le 10^5$和值高达$10^9$立即排除任何$O(NM)$配对策略。 即使对所有对进行一次二次传递也太大了。 任何可接受的解决方案都必须避免显式检查每一对，而是利用代数结构。 

当多个邮箱具有相同或主导参数时，会出现微妙的边缘情况。 例如，如果一个邮箱有两个较大的邮箱$y$和更大的$k$与另一个相比，它永远不是最佳的，但一个简单的算法可能仍然会考虑它。 另一个极端情况是当$x_i = 0$，这完全消除了乘法成本，并且只使得$k_j$与那家面包店相关。 相似地，$y_j = 0$消除对$x_i$，使此类邮箱对于所有面包店来说都可能是全局最佳的，无论其规模如何$x_i$。 

## 方法

 一个直接的方法是计算，对于每个面包店$x_i$，所有邮箱的最小值：$$\min_j (x_i \cdot y_j + k_j)$$并对这些值求和。 这是正确的，但要付出代价$O(NM)$，因为每个$N$面包店扫描所有$M$邮箱。 和$10^5$在两个维度上，这都需要$10^{10}$的评价，远远超出了可行的限度。 

关键的观察结果是该表达式是线性的$x_i$。 对于固定邮箱$j$，成本作为函数$x$是一条直线：$$f_j(x) = y_j \cdot x + k_j$$所以问题就变成了：对于每一个$x_i$，评估其中的最小值$M$点处的线$x_i$。 

这是一个经典的凸包技巧场景，但这里关键的简化是$x_i$value是独立的查询，排序后即可处理。 我们对两者进行排序$x_i$和斜率线$y_j$，然后保持较低的船体线。 由于查询是单调的，我们可以使用指针或二分搜索来有效地评估它们。 

几何解释是每个邮箱定义一条线，每个面包店都要求给定 x 坐标处的最低线。 排序确保我们只需要维护相关的候选行并丢弃那些永远不是最优的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(NM)$|$O(1)$| 太慢了|
 | 凸包技巧（排序查询）|$O((N+M)\log M)$或者$O(N+M)$|$O(M)$| 已接受 |

 ## 算法演练

 我们将问题转化为有效评估一组线性函数。 

## 算法演练

 1.解读每个邮箱$j$作为一条线$f_j(x) = y_j x + k_j$。 目标是找到对于每个$x_i$，该点所有线中的最小值。 这种重构将问题转化为重复的最小行查询。 
2. 对面包店进行排序$x_i$。 排序是必不可少的，因为它允许我们按升序查询行$x$，这使得能够增量维护候选结构。 
3. 按坡度对邮箱进行排序$y_j$。 这为以递增的斜率顺序构建较低的凸包做好了准备。 这种排序确保了当我们添加一条新线时，我们可以通过与之前存储的线的交点进行比较来决定它是否有用。 
4. 构建线的凸包。 每个新行都会与结构中的最后两行进行比较。 如果新行使前一行与所有将来的查询无关，我们将删除它。 这确保我们只保留对于某些范围来说是最佳的行$x$。 
5. 在处理增加的查询时保持船体上的指针$x_i$。 对于每个面包店值，只要下一行给出较小的值，就将指针向前移动。 这是可行的，因为最佳行索引是单调的$x$。 
6. 对于每个$x_i$，评估当前指针处的最佳行并将结果与​​答案模相加$10^9+7$。 

### 为什么它有效

 每个邮箱定义一个线性函数，最小过线性函数从下面看形成分段线性凹结构。 按斜率排序可确保线之间的交点顺序一致。 查询点的单调性保证了一旦一条线不再是最优的，它就不会再成为更大的最优线。$x$。 这可以防止回溯并允许船体线性遍历。 该算法永远不会丢弃对任何未来查询可能最佳的行，因此每个查询都会看到真正的全局最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def bad(l1, l2, l3):
    # check if l2 is unnecessary between l1 and l3
    # using cross multiplication to avoid floating point
    (m1, b1) = l1
    (m2, b2) = l2
    (m3, b3) = l3
    return (b3 - b1) * (m1 - m2) <= (b2 - b1) * (m1 - m3)

def solve():
    N, M = map(int, input().split())
    xs = [int(input()) for _ in range(N)]
    lines = []
    for _ in range(M):
        y, k = map(int, input().split())
        lines.append((y, k))

    xs.sort()
    lines.sort()

    hull = []
    for m, b in lines:
        hull.append((m, b))
        while len(hull) >= 3 and bad(hull[-3], hull[-2], hull[-1]):
            hull.pop(-2)

    def eval_line(line, x):
        return line[0] * x + line[1]

    ans = 0
    j = 0

    for x in xs:
        if j >= len(hull):
            j = len(hull) - 1
        while j + 1 < len(hull) and eval_line(hull[j + 1], x) <= eval_line(hull[j], x):
            j += 1
        ans = (ans + eval_line(hull[j], x)) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先将每个邮箱压缩为由斜率定义的线性函数$y_j$并拦截$k_j$。 它对这些线进行排序，以便可以增量地构造凸包。 这`bad`函数通过使用交叉乘法比较交点来删除永远不是最佳的中间线。 

在查询处理期间，面包店会进行排序，以便船体上的指针仅向前移动。 每个$x_i$在摊余常数时间内选择最佳线路。 模运算仅在累加时应用，因为单独的评估可能超出模数范围。 

一个常见的微妙之处是船体检查中的不等方向。 使用`<=`确保一致地删除共线或支配线，防止重复候选线导致不正确的指针移动。

 ## 边缘情况

 当$x_i = 0$，每个面包店都忽略斜坡，只看到$k_j$。 船体有效地减少到选取最小截线。 该算法自然地处理这个问题，因为评估$m \cdot 0 + b$总是返回$b$，因此指针收敛到最小截距。 

当邮箱有$y_j = 0$，它变成一条扁线。 如果它也有最小$k_j$，它在所有其他行中都占主导地位$x$。 在船体建造过程中，任何较高的截距平线都会被相交检查删除，只留下最佳的恒定线，这保证了正确的全局优势。 

当多个邮箱共享相同的坡度时，只有截距最小的邮箱才能在船体建造中幸存下来。 这`bad`函数删除多余的线，确保指针不会振荡或在等斜率候选之间错误地切换。
