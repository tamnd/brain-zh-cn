 ## 解决方案
 ## 问题理解

 我们得到一行文本，其中可能包含大写和小写英文字母以及空格。 任务是确定当我们忽略大写时，连续的字符序列“be”是否出现在文本中的任何位置。 

关键的转换是大小写并不重要，因此在搜索之前每个字符都应该被视为小写。 空格只是输入中的普通字符，但它们不能成为目标子字符串的一部分，因为我们专门寻找形成“be”的两个连续字母。 

输入大小最多为 1000 个字符，这对于竞争性编程标准来说是非常小的。 这立即排除了对线性扫描之外的效率的任何担忧。 即使是检查每个可能的子字符串的简单方法在限制范围内也已经足够了。 

主要的微妙之处是处理大小写标准化并确保我们只考虑连续的字母。 一个常见的错误是在原始字符串中搜索“be”而不转换大小写，这在输入“BE”或“Be”时会失败。 另一个错误是错误地跳过空格，从而破坏了邻接逻辑。 例如，“be”不应该匹配，因为字符在原始字符串中不连续。 

边缘情况包括即使字母彼此靠近但没有字母形成模式的字符串，例如“be”，以及匹配跨越不同情况的字符串，例如“bE”或“BE”。 像“b”或“e”这样的单字符字符串也必须正确返回“no”。 

## 方法

 一种简单的方法是将字符串标准化为统一的大小写，然后从左到右扫描它，检查每对相邻的字符。 如果任何一对等于“be”，我们立即得出答案是肯定的。 

暴力变体会显式测试长度为 2 的每个子字符串，并将其转换为小写后与“be”进行比较。 对于长度为 n 的字符串，它会检查 n - 1 个子字符串，每个子字符串的时间都是恒定的，给出线性复杂度。 即使是更简单的方法（例如生成所有子字符串）也是不必要的，但在给定约束的情况下仍然可以通过。 

关键的观察结果是，问题简化为固定长度 2 的简单模式搜索。不需要像 KMP 这样的高级字符串算法，因为模式是恒定大小的。 这会将任务折叠为对字符串的单次传递。

 | ---| ---| ---| ---|

 ## 算法演练

 1. 将输入字符串作为单行读取。 该字符串可能包含空格，我们不会将其删除，仅通过字符比较间接忽略以达到匹配目的。 
2. 将整个字符串转换为小写。 这确保了比较的统一并消除了以后基于案例的分支。 
3. 从索引 0 到 n - 2 迭代字符串。我们在 n - 2 处停止，因为我们总是检查一对连续的字符。 
4. 对于每个位置 i，检查 s[i] 是否为“b”且 s[i + 1] 是否为“e”。 这直接测试从 i 开始的子字符串是否与目标模式匹配。 
5. 如果找到任何这样的对，立即输出“yes”并终止程序。 
6. 如果循环结束后没有找到匹配项，则输出“no”。 

### 为什么它有效

 该算法依赖于以下不变量：原始字符串中子字符串“be”的每次出现都必须在某个索引对 (i, i + 1) 中显示为两个连续字符。 小写保留了字母之间的相等关系，因此原始字符串中的任何有效匹配都与转换后的字符串中的匹配完全对应。 由于我们检查所有相邻对，因此不会错过任何有效的事件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().rstrip("\n")
s = s.lower()

found = False
for i in range(len(s) - 1):
    if s[i] == 'b' and s[i + 1] == 'e':
        found = True
        break

print("YES" if found else "NO")
```该解决方案有效地读取输入并立即使用`.lower()`。 循环被仔细限制以避免访问时索引超出范围`i + 1`。 提前退出确保我们在发现模式后立即停止，尽管即使没有提前退出，复杂性仍然是线性的。 

一个常见的实现陷阱是忘记字符串中保留空格。 此代码可以正确处理该问题，因为空格永远不会匹配“b”或“e”，因此它们自然会失败比较，而不需要特殊处理。

 ## 边缘情况

 一个关键的边缘情况是子字符串以混合大小写形式出现。 对于像“bE”这样的输入，算法首先将其转换为“be”，然后相邻检查在索引 0 处检测到它并立即返回 YES。 这证实了标准化正确地统一了所有案例变体。 

另一个边缘情况是字母之间存在空格，否则会形成图案。 例如，“be”在归一化后变为“be”。 该循环仅检查相邻索引，因此它永远不会跨空间组合字符，并正确返回 NO。 

最后的边缘情况是非常短的字符串，例如“b”或“e”。 小写后，循环范围变空，因为长度减一为零或负数，因此不会发生迭代，并且函数正确返回 NO。
