 ## 解决方案
 ## 问题理解

 我们正在维护一个堆栈网格。 中的每个单元格$N \times N$board 存储垂直的字母堆栈，其中每次更新要么将字母推入堆栈，弹出顶部字母，要么询问当前堆栈是否有“主导”字母。 

如果查询的字母严格出现在堆栈中当前元素的一半以上，则在查询下该堆栈被认为是漂亮的。 

因此，每个操作都本地化到单个单元格，但关键的困难在于序列是动态的：推送和弹出会随着时间的推移改变堆栈高度，并且查询必须反映该堆栈中当前的字母多重集。 

约束是真实的信号。 网格很小（$N \le 100$），所以最多有10000个独立堆栈。 但操作次数可以达到$2 \cdot 10^5$。 这排除了堆栈的任何每次查询扫描，因为单个堆栈可以随着操作线性增长。 在最坏的情况下，重复推入一个单元格会创建一堆大小$2 \cdot 10^5$，并且每个查询扫描它都会立即超出时间限制。 

计算每个查询堆栈中的频率的简单方法会产生成本$O(k)$每个查询，其中$k$是堆栈高度，导致$O(Q^2)$在最坏的情况下。 

一个微妙的边缘情况来自于空堆栈上的删除。 对未触及的单元进行删除操作不会执行任何操作，但假设堆栈存在的粗心实现可能会引发错误或错误地将计数减少到零以下。 

另一个棘手的场景是在同一单元上交错操作：

 输入：```
0 a 0 0
0 b 0 0
2 a 0 0
1 0 0
2 a 0 0
```正确的行为需要跟踪准确的顺序：推送后`a`， 然后`b`，堆栈是`[a, b]`，所以这两个字母都不是多数； 出栈后，堆栈为`[a]`， 所以`a`成为主导。 

## 方法

 暴力解决方案很简单：对于每个单元，维护一个表示其堆栈的列表。 推送追加，弹出删除最后一个元素（如果存在），查询计算整个堆栈中目标字母的出现次数并检查它是否超过堆栈大小的一半。 

这是正确的，因为它直接模拟了定义。 问题是性能。 每个查询都需要扫描堆栈大小，在对抗情况下堆栈大小会增长到$O(Q)$。 高达$2 \cdot 10^5$操作，这变成了$O(Q^2)$，这太慢了。 

关键的观察是，我们不需要所有字母的完整频率信息，只需要当时查询的候选字母的频率信息。 然而，如果我们想动态验证删除情况下的多数，即使仅维护计数也是不够的，因为从堆栈中删除任意字母会随着时间的推移改变平衡。 

如果我们为每个单元格维护当前堆栈中字母的频率图，则结构会变得更简单。 然后每次入栈都会增加一个计数，每次弹出都会减少被删除的顶部字母的计数，并且我们还保持当前的堆栈大小。 这使得每次操作$O(1)$平均而言，每个查询也$O(1)$: 我们只检查是否`freq[l] > size/2`。 

唯一缺少的部分是知道在弹出期间要递减哪个字母，这需要存储实际的堆栈内容，而不仅仅是计数。 

这导致了最佳设计：每个单元存储一个堆栈（用于顺序）和一个频率字典（用于计数）。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（扫描每个查询的堆栈）|$O(Q^2)$|$O(Q)$| 太慢了|
 | 每个单元的堆栈+频率图|$O(Q)$|$O(N^2 + Q)$| 已接受 |

 ## 算法演练

 1.初始化一个大小的网格$N \times N$, where each cell contains an empty stack and an empty frequency map.

 This allows us to isolate operations per coordinate so that no global recomputation is required.
 2. 对于油漆操作$(x, y)$，将字母推入该单元格的堆栈中，并增加其频率计数器。 

堆栈确保我们稍后可以正确撤消此操作，并且计数器会在恒定时间内保存聚合信息。 
3. 对于删除操作$(x, y)$，检查栈是否非空。 如果为空，则不执行任何操作。 

如果不为空，则弹出顶部元素并减少其频率。 这保证了订单和计数之间的一致性。 
4. 查询：$(x, y)$带信$l$，计算当前堆栈大小。 如果为零，则输出“no”。 

否则检查是否`frequency[l] * 2 > size`。 这直接编码严格多数，无需浮点运算。 

### 为什么它有效

 每时每刻，每个单元格的堆栈都由其存储的列表精确表示，并且频率图与该堆栈中的多重字母集精确匹配。 推入和弹出操作保留了这种不变性，因为每次插入或删除都会一致地更新这两个结构。 因此，在回答查询时，频率图提供当前堆栈中查询字母的准确计数，并将其与堆栈大小的一半进行比较，正确确定它是否形成严格多数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, Q = map(int, input().split())
    
    grid = [[[] for _ in range(N)] for _ in range(N)]
    freq = [[dict() for _ in range(N)] for _ in range(N)]
    size = [[0 for _ in range(N)] for _ in range(N)]
    
    out = []
    
    for _ in range(Q):
        parts = input().split()
        s = int(parts[0])
        
        if s == 0:
            l = parts[1]
            x = int(parts[2])
            y = int(parts[3])
            
            grid[x][y].append(l)
            size[x][y] += 1
            freq[x][y][l] = freq[x][y].get(l, 0) + 1
        
        elif s == 1:
            x = int(parts[1])
            y = int(parts[2])
            
            if size[x][y] == 0:
                continue
            
            ch = grid[x][y].pop()
            size[x][y] -= 1
            freq[x][y][ch] -= 1
            if freq[x][y][ch] == 0:
                del freq[x][y][ch]
        
        else:
            l = parts[1]
            x = int(parts[2])
            y = int(parts[3])
            
            if size[x][y] == 0:
                out.append("no")
            else:
                if freq[x][y].get(l, 0) * 2 > size[x][y]:
                    out.append("yes")
                else:
                    out.append("no")
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案保留每个单元的堆栈以维持顺序并支持正确的弹出行为。 频率字典与堆栈更改同步更新，确保查询期间的恒定时间多数检查。 分开的`size`数组避免重复重新计算长度。 

一个微妙的实现细节是当字典条目的计数降至零时删除它们。 这对于正确性来说不是必需的，但它可以限制内存并避免在执行过程中误导键。`.get()`检查。

 ## 边缘情况

 一个关键的边缘情况是查询空堆栈。 该实现在访问频率图之前显式检查大小。 如果没有这个保护，天真的除法或查找可能会错误地将丢失的键视为零并继续进行，只有在仔细处理大小的情况下，这才是正确的。 

另一种情况是对空堆栈重复弹出操作。 由于操作必须是无操作，因此实现通过检查来避免下溢`size[x][y] == 0`在弹出之前。 这确保了堆栈和频率图永远不会发散。 

最后一个微妙的情况是字母从堆栈中完全消失。 当计数达到零时删除字典条目可以防止陈旧的密钥误导未来的逻辑，假设密钥的存在意味着积极性。
