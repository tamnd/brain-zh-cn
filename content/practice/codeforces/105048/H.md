 ## 解决方案
 ## 问题理解

 我们得到一个长字符串，代表长度的“文本”$N$。 除此之外，我们还得到了一组$M$不同的词。 所有单词组合起来的总长度是有界的，因此虽然单词可能很多，但它们的组合结构仍然是紧凑的。 

然后我们被问到$Q$问题。 每个问题给出一个区间$[l, r]$在主字符串内部，我们必须计算该间隔中完全包含的子字符串有多少与任何给定单词匹配。 每次出现的情况都是独立计算的，因此如果一个单词在不同位置多次出现，或者不同的单词重叠，则所有有效匹配都会影响答案。 

核心难点在于字符串和查询数量都很大，因此从头开始重新计算每个查询间隔内的匹配太慢。 隐藏的结构是，我们所关心的是从某个位置开始的子字符串是否与字典单词之一匹配，然后有多少个开始位置位于每个查询范围内。 

这些约束意味着解决方案必须在文本大小加上字典总长度上接近线性或近线性，每个查询的开销可能是对数。 任何平方$N$或以上$Q$立刻就不可能了。 

天真的尝试会扫描每个查询间隔并尝试所有子字符串匹配。 即使仅限于字典单词，根据所有单词检查每个位置也会给出最坏的情况$O(N \cdot M)$，这远远超出了限制。 

一个更微妙的失败案例来自重叠匹配。 例如，如果字符串是`"AAAAA"`单词包括`"A"`,`"AA"`， 和`"AAA"`，然后在每个位置都有多个匹配开始，并且幼稚的子字符串枚举要么错误地重复计数，要么花费太多时间扩展每个查询的所有可能性。 

另一个边缘情况是许多查询严重重叠。 如果我们独立地重新计算每个查询的匹配项，即使底层匹配项相同，重复的工作也会爆炸。 

## 方法

 关键的观察是每个有效答案都是由字典匹配的起始位置确定的。 如果我们知道，对于每个索引$i$, 有多少个单词开头$i$，那么每个查询就变成该数组上的简单范围总和。 

因此，问题简化为计算文本上的频率数组：对于每个位置，计算从那里开始匹配的字典单词数量。 

一种蛮力的方法是在每个位置尝试每个单词。 这导致$O(N \cdot \text{word length})$每个单词的总比较次数太大。 

许多具有共享前缀的模式的结构建议构建一个特里树。 我们可以在遍历 trie 时扫描一次文本，而不是在每个位置独立检查每个单词，这自然会合并重复的前缀。 这将重复的字符比较转换为共享的转换。 

我们构建一个所有单词的字典树，标记终端节点有多少个单词结束。 然后我们从每个位置开始扫描文本，在字典树中向前走，直到我们不再匹配为止。 每当我们到达终端节点时，我们都会记录一个单词在那里结束，这意味着有效的子串从初始位置开始。 

由于总字长的界限为$10^5$，所有单词的 trie 转换总数也是有界的，并且一旦发生不匹配，从某个位置开始的每次扫描都会停止。 这使得总工作量与总匹配转换成正比，而不是$N \cdot M$。 

一旦我们有了一个数组`cnt[i]`= 从位置开始的单词数$i$，我们构建一个前缀和。 每个查询$[l, r]$变成一次减法。

 | ---| ---| ---| ---|
 | 蛮力 |$O(N \cdot M \cdot L)$|$O(1)$| 太慢了|

 ## 算法演练

 1. 根据所有单词构建一个字典树。 每个节点存储字母 A 到 Z 的转换以及一个指示有多少单词在该节点结束的计数器。 这允许共享前缀的多个单词重用结构而不是重复工作。 
2.初始化一个数组`cnt`尺寸的$N$带零。 该数组将存储主字符串中每个位置开始的字典单词数量。 
3. 对于每个起始位置$i$在主字符串中，从以下位置开始逐个字符地遍历 trie$s[i]$。 如果字符存在，则每一步都会沿着特里树向下移动； 否则，立即停止，因为不再可能匹配。 
4. 每当我们到达一个标记一个或多个单词结尾的 trie 节点时，将该节点的终止计数添加到`cnt[i]`。 这捕获以位置开始的所有单词$i$并匹配目前看到的前缀。 
5. 对所有起始位置重复此过程。 trie 转换的总数受所有单词的总长度限制，因为每个步骤要么沿着有效的字典前缀前进，要么停止。 
6. 构建前缀和数组`cnt`。 这允许回答任何查询$[l, r]$通过计算在常数时间内$\sum_{i=l}^{r} cnt[i]$。 
7. 对于每个查询，输出前缀和的差值。 

### 为什么它有效

 字典单词的每个有效出现都恰好对应一对：起始位置$i$以及从那里开始匹配的单词。 trie 遍历来自$i$准确地枚举这些单词而不重复，因为每个单词对应一个唯一的终端节点路径。 前缀求和步骤不会改变计数，它仅聚合时间间隔内的贡献。 由于每场比赛只计算一次`cnt[i]`，并且每个查询精确地对里面的那些位置求和$[l, r]$，结果正确。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("next", "end")
    def __init__(self):
        self.next = {}
        self.end = 0

def solve():
    N, M, Q = map(int, input().split())
    s = input().strip()

    root = Node()

    # build trie
    for _ in range(M):
        w = input().strip()
        cur = root
        for ch in w:
            if ch not in cur.next:
                cur.next[ch] = Node()
            cur = cur.next[ch]
        cur.end += 1

    cnt = [0] * N

    # scan from every position
    for i in range(N):
        cur = root
        j = i
        while j < N:
            ch = s[j]
            if ch not in cur.next:
                break
            cur = cur.next[ch]
            if cur.end:
                cnt[i] += cur.end
            j += 1

    # prefix sums
    pref = [0] * (N + 1)
    for i in range(N):
        pref[i + 1] = pref[i] + cnt[i]

    out = []
    for _ in range(Q):
        l, r = map(int, input().split())
        out.append(str(pref[r] - pref[l - 1]))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```trie 结构确保共享前缀不会被重复重新计算。 每个节点的`end`value 聚合了此时完成的单词数量，因此字典中的重复项（如果存在）自然会被处理。 扫描循环在不匹配时立即停止，以防止不必要的遍历。 

前缀和数组将索引移动一位，以便范围查询成为干净的减法，而不会降低一的复杂性。

 ## 边缘情况

 一个重要的边缘情况是每个单词都是单个字符。 在这种情况下，字符串中的每个位置都可能匹配多个单词，并且 trie 退化为单级分支结构。 该算法仍然表现正确，因为每个位置都独立贡献`cnt[i]`，并且前缀和在没有交互的情况下累积这些贡献。 

另一种情况是单词共享长前缀但较晚发散，例如`"ABCDE", "ABCDF", "ABCDG"`。 trie 确保共享前缀`"ABCD"`每个起始位置遍历一次，并且仅在最后一步发生分支。 即使多个单词可能在同一深度匹配，`end`终端节点的计数器确保所有数据都正确计数，无需单独扫描。
