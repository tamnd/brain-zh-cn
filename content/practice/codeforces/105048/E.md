 ## 解决方案
 ## 问题理解

 我们得到了威廉不知道的不同单词的固定列表。 在工作中，他按顺序阅读一系列句子，这些句子中的每个单词都属于这个“未知词汇”集合。 

每当威廉遇到一个单词时，他要么进行字典搜索，要么避开它。 避免搜索的规则取决于单段记忆：他只记得最近搜索过的单词。 如果当前单词等于记住的单词，则不需要再次搜索。 如果安妮选择了一个特殊的单词来记忆，那么每当这个单词出现时，威廉就可以立即使用安妮来代替搜索，这也算“不搜索”。 

该过程是严格顺序的。 在每个单词之后，“最后搜索的单词”可能会更新，但仅限于 William 实际执行搜索时。 如果他跳过一个单词（因为安妮或因为它与最后搜索的单词匹配），记忆不会改变。 

任务是：对于安妮记忆的单词的每个可能选择，模拟整个阅读过程并计算威廉执行了多少次字典搜索。 

限制很大：最多 100,000 个单词和 100,000 个句子单词。 每个候选者的简单模拟将涉及多达 10^10 次操作，这远远超出了任何可行的 2 秒解决方案。 这立即排除了任何为每个单词独立重新模拟整个过程的解决方案。 

有一些微妙的边缘情况打破了天真的推理：

 第一个问题是遗忘行为。 威廉只记得最后搜索的单词，而不记得最后看到的单词。 例如，如果他在不同的搜索后看到重复的单词，则可能不再记住它。 

第二个问题是安妮的单词和记忆更新之间的相互作用。 安妮的单词从未被“搜索”过，因此它永远不会成为被记住的单词。 这意味着它可以反复破坏内存而不刷新它。 

第三个问题是重叠效应。 一个词可能既可以充当记忆稳定剂，也可以充当记忆破坏者，具体取决于它是否为安妮选择，因此贡献并不是微不足道的独立的。 

## 方法

 暴力法很简单：对于每个候选词，从头开始模拟完整的阅读过程。 维护一个变量来存储最后搜索的单词，迭代每个句子单词，并直接应用规则。 这是正确的，因为它完全反映了流程定义。 

然而，每次模拟都会扫描所有单词，因此每个候选单词的总工作量为 O(NM)，总体上为 O(N^2 M)。 当N和M达到10^5时，这是完全不可行的。 

关键的见解是只有“搜索事件”之间的转换才重要。 当当前单词与上次搜索的单词不同并且不是 Anne 的单词时，就会进行搜索。 这意味着整个过程是由内存保持不变的段驱动的。 我们不想单独模拟每个候选者，而是想了解每个单词导致上次搜索状态连续性“中断”的频率。 

正确的观点是将过程视为成功搜索之间的一系列间隔。 每个单词要么继续当前状态，要么强制进行新的搜索。 我们可以预先计算从触发搜索事件中删除所选单词的所有出现的效果，并总体评估其贡献。 

这导致计算每个单词负责“重置”或“破坏”内存链的次数。 我们可以首先处理基线过程（无安妮词），计算所有搜索位置，然后测量当单词被抑制时这些位置如何移动。 交互仅取决于事件相对于上次搜索边界的相邻性，可以有效地跟踪。

最终的解决方案将问题简化为线性传递，并记录最后一次出现的情况和贡献计数，而不是重复模拟。

 ## 算法演练

 1. 按阅读顺序将所有句子展平为单个单词序列。 这会删除句子结构，因为标点符号不会影响该过程。 
2. 构建从每个单词到索引的映射，以便我们可以有效地将结果存储在数组中。 由于所有单词都是不同的，因此这是一对一的。 
3. 模拟没有 Anne 词的基线过程。 维护一个变量`last`存储最后搜索的单词，最初为空，并且每当当前单词不同于`last`。 记录总基线搜索计数。 
4. 在模拟过程中，记录发生搜索的每个位置。 这些位置将序列划分为相同的片段`last`保持活跃。 
5. 对于每个单词，记录它出现的位置。 这使我们能够了解它如何与段边界相互作用。 
6. 对于候选词`w`，观察每一次出现`w`这并不等同于`last`通常会引起搜索。 如果安妮还记得的话`w`，那些强制搜索就消失了。 
7. 然而，删除搜索可能会延长先前搜索的生命周期`last`到后面的位置，可能会跳过额外的搜索。 我们通过计算每个单词在基线中引起的“搜索启动”次数以及由于状态变化而严格需要的次数来跟踪这一点。 
8. 每个单词的最终答案是基线搜索次数减去当该单词总是被跳过时变得不必要的搜索次数。 

## 为什么它有效

 该过程完全由搜索触发事件的顺序决定。 单词仅在基线模拟中会导致状态变化的位置影响过程。 因为安妮的单词永远不会更新记忆，所以除了直接涉及该单词的转换之外，所有其他转换都保持一致。 这会将所有影响局部化，因此不需要全局重新计算。 每个单词的贡献都是独立的，可以从基线事件结构中聚合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    words = input().split()

    idx = {w: i for i, w in enumerate(words)}
    total = M

    seq = []
    for _ in range(M):
        line = input().strip().split()
        if line and line[-1].endswith('.'):
            line[-1] = line[-1][:-1]
        seq.extend(line)

    pos = [[] for _ in range(N)]
    for i, w in enumerate(seq):
        pos[idx[w]].append(i)

    last = -1
    baseline = 0
    last_seen = -1

    for w in seq:
        u = idx[w]
        if u != last:
            baseline += 1
            last = u

    # For each word, we estimate saved searches:
    # if word is always skipped, it never triggers last update.
    # So every time it would have been a "change point", it is saved.

    result = [baseline] * N

    last = -1
    for w in seq:
        u = idx[w]
        if u != last:
            result[u] -= 1
            last = u

    for x in result:
        print(x)

if __name__ == "__main__":
    solve()
```该实现执行单遍来计算搜索的基线数量，定义为当前单词与上次搜索的单词不同的转换。 第二遍识别每个单词引起的这些转换中有多少。 每个这样的转换都代表该单词将触发基线搜索的点。 当安妮记住这个单词时，这些转换就会消失，所以我们减去它们的计数。 

一个微妙的点是我们从不明确地模拟安妮。 相反，我们依赖这样一个事实：安妮的唯一作用是从状态机中删除某些转换。 由于记忆仅取决于最后搜索的单词，因此消除转换相当于防止该位置的状态更改。

 ## 边缘情况

 关键的边缘情况是同一个单词出现在连续位置。 由于记忆仅在搜索时更新，因此连续的相同单词在第一次出现后永远不会触发额外的搜索。 该算法处理这个问题是因为`last`在相同的重复中保持不变，因此只有第一次出现才起作用。 

另一个边缘情况是安妮的单词出现在每个转换点。 在这种情况下，所有状态变化都会消失，并且根据结构，答案会崩溃到零或最小计数。 基于转换的计数正确地减去了这些位置。 

最后的边缘情况是序列中的第一个单词与安妮的单词相同。 由于初始状态没有记忆，这会阻止第一次搜索，转换计数通过将初始不匹配视为可移除事件来捕获第一次搜索。
