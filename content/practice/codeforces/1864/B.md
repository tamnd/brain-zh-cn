 ## 解决方案
 ## 问题理解

 我们得到一个字符串和两种移动方式，让我们以受限的方式重新排列它的字符。 一个动作交换相隔两个位置的字符，另一个动作反转固定长度的连续块$k$。 我们可以以任何顺序应用这些操作任意次数，并且我们想要可以到达的字典顺序最小的字符串。 

关键的困难在于这些操作乍一看不允许任意排列。 2位交换操作仅涉及相同奇偶校验的索引，而反转操作仅混合长度段$k$，它可以以微妙的方式与奇偶约束相互作用。 

输入大小将我们推向每个测试用例的线性或近线性解决方案。 由于所有测试用例的总长度是$10^5$，任何尝试模拟操作或每个位置运行类似排序行为的解决方案都必须避免$O(n^2)$行为。 我们应该期待一种解决方案，将问题简化为对位置进行分组并对这些组内的字符进行排序。 

一个天真的错误是假设我们可以自由地对整个字符串进行排序。 例如，在这样的情况下$n=5, k=3$，并非所有排列都是可以实现的，盲目排序会违反约束。 另一个微妙的失败来自于忽略奇偶校验结构：交换$i$和$i+2$意味着奇数索引处的字符永远不会与偶数索引混合，因此将字符串视为单个池会失去正确性。 

## 方法

 如果我们忽略约束并模拟所有允许的操作，我们将探索从初始字符串可到达的所有排列的状态图。 每个州最多有$O(n)$转换，并且状态数是阶乘$n$，所以这是完全不可行的。 

即使我们尝试贪心模拟，重复应用字典顺序改进操作，我们很快就会遇到麻烦：反转操作可以撤销局部进展，并且系统不会以任何简单的单调方式收敛。 

突破来自于将问题分解为两个独立的结构效应。 交换$i \leftrightarrow i+2$创建两个独立的链：所有偶数索引可以相互排列，所有奇数索引可以相互排列，但不能混合。 长度取反运算$k$允许我们以受控的方式对这些链上的字符进行重新排序，并且$k$决定两条链是否相互作用。 

如果$k$是奇数，反转段会保留奇偶位置，因此偶数和奇数位置永远保持隔离。 在这种情况下，我们只能对每个奇偶校验类中的字符进行独立排序。 

如果$k$是偶数，反转段会翻转块内的奇偶校验对齐，这有效地允许奇偶校验类之间的交换。 这使得系统完全连接：任何字符最终都可以移动到任何位置，因此我们可以对整个字符串进行全局排序。 

所以问题就简化为：

 当$k$为奇数时，将偶数索引和奇数索引的字符分别排序；

 什么时候$k$是偶数，对整个字符串进行排序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| 指数| 指数| 太慢了 |
 | 奇偶校验 + 排序洞察 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 检查是否$k$是偶数还是奇数。 这决定了头寸是否可以在奇偶校验组之间交叉。 仅靠交换 2 规则就可以保留奇偶性，因此只有反转才会改变结构。 
2.如果$k$是偶数，收集字符串的所有字符，排序，然后按照从小到大的顺序写回。 推理是这些操作生成一个完全连接的排列组，因此每个排列都是可达的。 
3.如果$k$是奇数，将字符拆分为两个多重集：一个包含偶数索引处的字符，另一个包含奇数索引处的字符（使用基于 0 的索引）。 每个集合都可以独立排列，因为$+2$交换，但它们不能交互。 
4. 对两个多重集独立排序。 
5. 通过从左到右填充位置并从相应的奇偶校验池中获取字符来重建最终字符串。 

核心推理步骤是在奇数中$k$在这种情况下，每个操作都会保留奇偶校验类。 交换$i \leftrightarrow i+2$显然是这样。 长度-$k$奇数逆转$k$围绕中心对称映射索引偏移，保留每个位置的奇偶性。 因此，任何操作都不会将字符从偶数索引移动到奇数索引，反之亦然。 

什么时候$k$是偶数，反转会翻转段内的奇偶校验，因此重复应用允许奇偶校验在整个字符串中混合。 与本地交换相结合，这产生了完整的排列能力。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = list(input().strip())

        if k % 2 == 0:
            s.sort()
            print("".join(s))
        else:
            even = []
            odd = []

            for i, ch in enumerate(s):
                if i % 2 == 0:
                    even.append(ch)
                else:
                    odd.append(ch)

            even.sort()
            odd.sort()

            res = []
            ei = oi = 0
            for i in range(n):
                if i % 2 == 0:
                    res.append(even[ei])
                    ei += 1
                else:
                    res.append(odd[oi])
                    oi += 1

            print("".join(res))

if __name__ == "__main__":
    solve()
```该解决方案首先在奇偶校验上分支$k$，即结构分界线。 在偶数情况下，全局排序就足够了，因为所有字符都可以相互访问。 在奇怪的情况下，我们明确维护两个排序池并通过交替奇偶校验位置进行重建。 重建步骤是线性的并且避免了任何操作模拟。 

一个微妙的实现点是索引：奇偶校验分割必须与Python中基于0的索引一致。 在这里混合基于 1 的推理会错误地交换组。 

## 工作示例

 ### 示例 1

 输入：`4 2, nima`自从$k=2$是偶数，我们全局排序。 

| 步骤| 字符串状态 | 行动|
 | ---| ---| ---|
 | 开始| 尼玛| 初始|
 | 排序 | 目标 | 重新排序所有字符 |

 输出是`aimn`。 

这演示了完全连接的情况：所有字符都是可互换的。 

### 示例 2

 输入：`5 3, panda`这里$k=3$是奇数，因此保留奇偶性。 

我们分开：

 偶数索引：p(0)、n(2)、a(4)

 奇数索引：a(1)、d(3)

 | 步骤| 连池| 奇池| 行动|
 | ---| ---| ---| ---|
 | 开始| p n a | 广告 | 分裂|
 | 排序 | 一个 n p | 广告 | 排序池 |
 | 重建 | a 和 p | 交替填充 | 构建|

 最终字符串是`aandp`。 

这证实了跨奇偶校验的混合是不可能的，因此我们仅在每个奇偶校验类别内进行优化。

 ## 边缘情况

 对于像这样的字符串`aaaaa`与任何$k$，这两个操作变得无关紧要，因为所有排列都是相同的。 算法仍然进行分割或排序，但结果保持不变，因此不会发生错误的重排。 

对于小字符串，其中$n = 2$或者$n = 3$，基于奇偶校验的拆分仍然可以正确运行，因为其中一个组可能为空，并且对空列表进行排序是无害的。 重建只是从非空池中提取。 

对于交替模式，例如`ababab`与奇数$k$，拆分准确地保留了结构，奇偶校验组内的排序可能会显着改变排列，但由于交换 2 连接性而仍然可达。
