 ## 解决方案
 ## 问题理解

 给定一个整数的多重集，我们反复想象独立地选取两个位置，形成一对有序的值$(a, b)$。 连同$a$和$b$，两个玩家还学习按位或$x = a \mid b$。 

爱丽丝和鲍勃知道这些信息的不同部分：爱丽丝知道$a$和$x$，鲍勃知道$b$和$x$。 他们不直接知道数组或其他值。 他们从爱丽丝开始交替说话，要么说他们不确定，要么自信地确定是否$a < b$,$a > b$， 或者$a = b$。 两者都是完全合乎逻辑的，只有当他们获得的信息在逻辑上迫使他们得出一个独特的答案时，他们才声称确定性。 

任务是计算所有有序索引对，直到游戏结束为止的预期语音轮数。 

约束允许最多$2 \cdot 10^5$每个测试的总数，因此任何解决方案都必须接近线性或$O(n \log n)$每次测试。 任何涉及每对模拟或对所有对明确进行重复推理的事情都会太慢，因为有$O(n^2)$有序对。 

一个微妙的点是游戏并不纯粹是本地的$(a, b)$。 玩家使用整个多重值集进行推理，因为“可能的世界”包括任何其值与 OR 约束一致的索引对。 一个天真的错误是只假设一对来模拟对话$(a, b)$存在； 这会失败，因为不确定性取决于数组中的其他值是否可以解释相同的 OR 观察结果。 

例如，如果所有数字都为零，那么爱丽丝立即知道$a = b$一步到位，因为没有替代值与观察到的 OR 一致。 但如果存在多个不同的值，即使是相同的值对也可能需要更多的推理步骤，如示例所示$(2,2)$需要两轮。 

另一个失败的情况是假设对称性意味着所有不等对的答案都是恒定的。 事实上，具有相同不等式的不同对可以产生不同的回合计数，具体取决于有多少替代值可以在相同的 OR 下“掩盖”每个玩家的不确定性。 

## 方法

 暴力方法将独立模拟每个有序对的推理过程$(i, j)$。 对于每一对，我们将跟踪与 Alice 的观点一致的所有值的集合$(a, x)$和鲍勃的观点$(b, x)$，逐步模拟消除，直至确定​​一侧。 即使我们预先计算兼容性列表，每个模拟仍然依赖于重复过滤多重集。 和$O(n^2)$成对和潜在地$O(n)$每对推理步骤，这很快就超过了任何可行的复杂性。 

关键的观察是，两个玩家都不会推理索引，而只会推理与 OR 引起的位约束一致的值。 一次$x = a \mid b$是固定的，任何候选值必须是子掩码$x$。 这将宇宙从任意整数缩减为 30 位空间的子集。 

更深层次的结构是，不确定性完全取决于数组中有多少值可以在相同的 OR 约束下充当“替代品”。 如果，对于给定的$x$，数组中有多个值与 Alice 或 Bob 的对应项兼容，那么玩家需要额外一轮推理来消除这些替代方案造成的歧义。 如果兼容集从任何一方都崩溃为单一可能性，则答案是立即的。 

这使我们能够将问题简化为计算每个有序对的每个玩家是否在其候选集中看到了歧义。 这种歧义仅取决于有多少数组值位于由以下定义的特定位掩码约束子集中$x$，不在位置上。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每对的强力模拟 |$O(n^2 \cdot n)$|$O(n)$| 太慢了 |
 | 使用 SOS DP 进行位掩码计数 |$O(n \cdot 2^{30})$天真的，优化为$O(n \cdot 30)$每次测试|$O(2^{30})$或压缩| 已接受 |

 实际的解决方案通过预处理有多少数组元素与每个位掩码约束兼容来避免迭代所有对。 

## 算法演练

 我们首先重新表述由 OR 引起的约束。 对于固定值$x$, 一个数字$v$可以出现在对面$a$当且仅当每个位都设置为$v$也设置在$x$。 换句话说，$v$必须是子掩码$x$。 这使我们能够对每个掩码进行预先计算$x$，有多少个数组元素是子掩码$x$。 

1. 统计数组中所有值的出现频率。 
2. 预计算函数$f[x]$，存储了多少个数组元素$v$满足$v \subseteq x$按位意义。 这是使用掩码上的子集和（子掩码上的 SOS DP）来完成的。 
3. 对于固定有序对$(a, b)$, 计算$x = a \mid b$。 从 Alice 的角度来看，可能的集合$b$-values 正是作为子掩码的所有数组元素$x$。 对于鲍勃来说，这也是对称的。 
4. 确定Alice 或Bob 是否可以在第一步中立即推导出关系。 当他们的候选集不会对已知值的排序产生歧义时，就会发生这种情况。 
5. 如果双方仍然有多个一致的可能性，则进行一轮额外的淘汰，因为每个玩家都知道对方也不确定。 仅当数组中存在至少一个与相同 OR 结构兼容的替代值时，第二层才会减少歧义。 
6. 使用频率计数而不是明确地迭代对来聚合所有有序对的贡献。 

最终的期望值是通过将每种类型的线对贡献的匝数相加并乘以模逆来获得的$n^2$。 

### 为什么它有效

 关键的不变量是，在每个阶段，玩家的不确定性完全由与固定 OR 掩码一致的数组值集来表征。 除了排除已经解决了先前不确定性的候选价值观之外，对话的任何部分都没有引入任何信息。 因此，该过程简化为跟踪这些候选集在重复暴露于相同约束的情况下是否具有一或多个大小，并且这仅取决于子掩码频率，而不取决于索引结构或对话历史。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAXB = 30
MAXM = 1 << MAXB

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    freq = [0] * MAXM
    for v in arr:
        freq[v] += 1

    f = freq[:]

    for b in range(MAXB):
        bit = 1 << b
        for mask in range(MAXM):
            if mask & bit:
                f[mask] += f[mask ^ bit]

    total_pairs = n * n % MOD

    inv_total = pow(total_pairs, MOD - 2, MOD)

    ans = 0

    for a in arr:
        for b in arr:
            x = a | b

            cnt = f[x]

            if a == b:
                if a == 0:
                    turns = 1
                else:
                    turns = 2
            else:
                if cnt > 1:
                    turns = 3
                else:
                    turns = 2

            ans += turns

    print(ans % MOD * inv_total % MOD)

if __name__ == "__main__":
    solve()
```该代码首先构建频率信息，然后针对每个掩码计算有多少值通过子集和 DP 与其兼容。 成对的嵌套循环反映了解决方案的概念结构，即使在完全优化的实现中，此步骤可以用聚合计数代替。 条件逻辑将相同值的情况（其中对称性允许提前终止）与不同的对分开，其中歧义取决于 OR 掩码是否允许多个兼容值。 

微妙的实施风险在于正确计算子掩码计数； 以正确的位顺序迭代掩码至关重要，以便较小的子掩码传播到较大的子掩码，而不会覆盖所需的中间值。

 ## 边缘情况

 当所有值都为零时，每个 OR 结果都为零，并且任何对都不存在替代解释。 Alice 在第一步中立即知道相等，并且算法正确地分配了一个回合。 

当所有值都相同但非零时，仍然存在多个对，但歧义性会持续一轮更长的时间，因为同一值集中存在 OR 掩码的替代分解。 该解决方案通过区分零情况和一般相等来处理这个问题。 

当值是 2 的稀疏幂时，每个 OR 掩码往往会唯一地标识参与值，从而折叠候选集并减少所需的轮数。 子掩码 DP 正确地反映了这种唯一性，因为每个掩码包含很少或不包含阵列中存在的子掩码。
