 ## 解决方案
 ## 问题理解

 网格可以看作是一个矩形图，其中每个单元都是连接到其四个正交邻居的节点。 有些节点包含羊，有些节点包含狼，其余的为空。 狼可以自由地一步步穿过空的牢房，但一旦我们放置了狗，它们就无法穿过它们。 从运动的角度来看，羊和狗都是静态障碍物。 

任务是决定我们是否可以将狗放入空单元格中，以便仅通过非狗单元格的四个方向移动，不存在从任何狼到任何羊的路径。 如果可能的话，我们必须输出一种有效的狗放置配置。 如果没有，我们报告不可能。 

约束允许最多 500 x 500 的网格，因此单元总数最多为 250,000 个。 任何对每个单元执行少量恒定量的图探索的解决方案都可以，但任何试图单独重新计算每只狼或每只羊的可达性的解决方案仍然是可以接受的，前提是小心地实现为单次遍历。 在狼和羊之间进行简单的成对可达性检查是立即不可行的，因为这意味着在最坏的情况下最多可达 O(R^2 C^2) 行为。 

一个微妙的一点是狼不受个体限制。 一只狼到达任何一只羊都会使配置无效，并且多只狼可以隐式合作，因为可达性纯粹是基于图的。 

当输入中狼与羊相邻时，就会出现主要的边缘情况。 由于我们只允许将狗放入空牢房中，因此如果它们已经是相邻的，则无法将它们分开。 例如，在一个 2 × 2 的网格中，狼和羊相邻，答案一定是不可能的。 另一个重要的边缘情况是，当狼包围一只羊时，从狼到那只羊的所有路径都经过一个空的走廊单元。 这条走廊必须被封锁，解决方案必须正确识别狗并将其放置在那里。 

## 方法

 一个蛮力的想法是使用多源 BFS 来模拟所有狼的运动，标记所有可到达的单元格。 在计算出狼的完整可到达区域后，我们只需检查其中是否有羊。 如果可以到达一只羊，我们会尝试让狗挡住路径并重复。 然而，这变得很复杂，因为动态地决定将狗放置在哪里需要解决全局最小切割样式问题，而这在这里是不必要的。 

关键的观察使一切变得简单：我们不需要在全球范围内控制狼和羊之间的所有路径。 我们只需要确保没有狼可以通过相邻的空单元直接进入羊单元。 如果狼能到达一只羊，那么一定存在一条路径，最后一步从它的四个邻居之一进入羊。 这意味着，如果我们通过阻止羊的空邻居来防止任何狼和任何羊之间的邻接，那么整个问题就解决了。 

这将问题简化为局部施工问题。 我们扫描网格。 如果任何狼已经与一只羊相邻，则无法在它们之间插入狗，因此答案立即不可能。 否则，我们将狗放在与羊相邻的每个空牢房中。 这些狗充当屏障，防止狼将来进入羊群区域。 由于狼无法穿过狗，并且所有羊现在都与通向狼的相邻空单元格隔离，因此不存在任何路径。 

蛮力探索将模拟全局可达性，但网格的结构确保只有直接邻接才重要，因为任何更长的路径都必须首先经过羊的邻居。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 强力 BFS 可达性检查 | 每次搜索 O(RC)，可能为 O(R^2C^2) | O(RC) | 太慢/不必要|
 | 最佳局部阻塞 | O(RC) | O(RC) | 已接受 |

 ## 算法演练

 我们将网格视为可变结构并直接构建最终的排列。 

1. 将输入网格复制到可变数组中，这样我们就可以在不丢失原始信息的情况下放置狗。 这是必要的，因为我们必须保护所有的羊和狼不变。 
2. 遍历网格中的每个单元格。 每当我们发现一只羊时，就检查它的四个相邻的牢房。 
3. 如果任何邻居是狼，我们立即得出答案是不可能的。 这是因为我们不能将狗放入羊或狼的牢房中，因此邻接关系无法修复。 
4. 如果邻居是空的，我们将其转换为狗。 这确保了狼未来向羊移动的任何尝试都会在边界处被阻止。 我们热切地为所有羊这样做，因为多只羊可能共享边界单元。 
5.处理完所有单元格后，输出修改后的网格。 

我们不需要显式模拟狼的原因是，从狼到羊的任何有效路径都必须经过羊的邻居。 通过确保所有此类邻居都被阻止，我们一次性消除了所有可能的路由。 

### 为什么它有效

 从狼到羊的任何路径都是以羊单元结束的相邻单元的序列。 这条路径中倒数第二个单元格一定是那只羊的邻居。 如果邻居是狗或墙，则路径不存在。 因此，路径存在的唯一方式是羊的某个邻居要么是狼，要么是保持畅通无阻的空牢房。 我们明确禁止狼邻接并将所有空邻居转换为狗，因此仍然不可能有效地最后一步进入羊。 这个不变量同时适用于所有羊，因为阻塞是全局完成的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    R, C = map(int, input().split())
    grid = [list(input().strip()) for _ in range(R)]
    
    dirs = [(1,0), (-1,0), (0,1), (0,-1)]
    
    for i in range(R):
        for j in range(C):
            if grid[i][j] == 'S':
                for di, dj in dirs:
                    ni, nj = i + di, j + dj
                    if 0 <= ni < R and 0 <= nj < C:
                        if grid[ni][nj] == 'W':
                            print("No")
                            return
                        if grid[ni][nj] == '.':
                            grid[ni][nj] = 'D'
    
    print("Yes")
    for row in grid:
        print("".join(row))

if __name__ == "__main__":
    solve()
```该实现直接遵循前面描述的网格扫描。 关键细节是，修改是在扫描时就地完成的，但这是安全的，因为将空细胞变成狗只会加强保护，而不会为狼引入新的路径。 

边界检查确保我们不会访问无效索引。 一旦确定不可能，尽早退出检测相邻狼可以避免不必要的处理。 

## 工作示例

 ### 示例 1

 输入：```
3 3
S.W
...
W.S
```我们扫描每只羊并检查邻居。 

| 单元格 (i,j) | 类型 | 邻居检查结果 | 行动|
 | --- | --- | --- | --- |
 | (0,0) | (0,0) | S | 右边是W | 不可能检测到|

 由于狼与羊相邻，因此我们立即输出 No。这证实了邻接是致命配置。 

### 示例 2

 输入：```
3 3
S..
...
..W
```我们在 (0,0) 处处理羊。 

| 单元格 (i,j) | 类型 | 邻居扫描 | 网格变化|
 | --- | --- | --- | --- |
 | (0,0) | (0,0) | S | (1,0),(0,1) 是“.” | 将 D 置于 (1,0),(0,1) |

 最终网格变为：```
SD.
D..
..W
```阻挡后没有羊与狼相邻，因此输出为 Yes。 这表明局部阻塞完全分离了组件。

 ## 边缘情况

 狼羊直接邻接是最严重的故障模式。 对于这样的输入：```
2 2
SW
..
```该算法检查单元格 (0,0)，看到一只羊，并立即在其右侧发现一只狼。 在任何修改之前它都会返回 No。 这确保我们永远不会错误地尝试“修复”不可能的配置。 

第二种情况是多只羊共享一个边界单元。 在像这样的网格中：```
3 3
S.S
...
W.W
```在每只羊的加工过程中，与两只羊相邻的中间排空单元被转化为狗。 即使同一单元格可能被多次考虑，重新分配“.” 到“D”是幂等的，因此最终的网格保持一致并完全阻塞。
