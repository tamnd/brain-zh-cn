 ## 解决方案
 ## 问题理解

 我们给出了一个大小为的矩形网格$n \times m$，以及最初放置在单元格中的单个令牌（怪物）$(a, b)$。 两名玩家交替做出决定，但不是通常意义上的交替回合，而是每个回合由两个阶段组成：首先沿整行或列线切割当前矩形，然后将怪物重新定位到剩余矩形内的任何位置。 

切割是唯一可以减小电路板尺寸的操作。 每次切割后，对手可以在剩余的矩形内自由地重新定位怪物，这实际上意味着从下一回合开始，其位置不再受先前移动的限制。 游戏持续进行，直到矩形变成一个单元格，目标是确定在最佳游戏下此过程需要多少回合，其中一个玩家尝试最小化切割次数，另一个玩家尝试最大化切割次数。 

一个关键的观察结果是，在第一次切割之后，由于怪物可以任意移动，因此确切的初始位置失去了长期意义。 这从根本上提出了当每次切割只能保证保留包含所选点的部分时，矩形可以多快地缩小的问题，但对手总是会重新定位以使未来的切割尽可能低效。 

限制条件$n, m \le 10^9$立即排除任何网格模拟或逐步还原。 任何可行的解决方案都必须在每个测试用例的恒定时间内计算答案，可能使用对数推理或封闭式表达式。 

例如，当一维已经很小时，就会出现微妙的边缘情况$1 \times m$或者$n \times 1$。 在这种情况下，只有一个方向的切割是可能的，并且假设两个维度同时收缩的贪心对称论证可能会导致计数过多。 

另一个棘手的情况是当起始位置靠近边缘时。 例如，在一个$2 \times 7$与怪物在第 2 列的网格相比，早期的最佳切割可能会隔离出比怪物集中开始时小得多的子网格。 一种幼稚的方法，忽略了$(a, b)$在这种情况下完全会失败，因为第一步很特殊并且取决于不对称性。 

## 方法

 暴力解释将游戏状态模拟为矩形，并重复尝试每种可能的水平或垂直切割，始终假设对手会以敌对方式重新定位怪物。 每个状态定义为$(n, m)$，并且过渡会尝试所有可能的方法来分割矩形，同时将怪物保持在一侧。 然而，即使代表所有州也已经给出$O(nm)$的可能性，并且每次转换都取决于扫描可能的切割位置，这使得它完全不可行。 

关键的见解是，在第一步之后，怪物的自由消除了位置限制，因此问题会以最糟糕的方式反复将维度减半。 最优策略变为：每次切割减少行数或列数，并且对手确保剩余的块始终是切割后可能的更大的段。 

从第二回合开始，该过程的行为就像重复切割一个矩形，其中每次移动都会减少$n$或者$m$通过选择最小化进度的拆分。 这将问题转化为每个维度上的对数收缩过程。 唯一的复杂之处是第一步，即初始位置$(a, b)$允许潜在的不对称第一次切割，可以立即将一个维度减少到$a$或者$n-a+1$，对于列也类似。 

因此，该解决方案简化为评估通过第一次切割获得的四个候选起始矩形，然后计算需要多少次切割才能将每个结果矩形缩小到$1 \times 1$，始终假设尺寸的最佳交替收缩。

 ## 算法演练

 我们单独对待第一个动作，因为这是怪物初始位置限制切入的唯一时刻。 

1. 考虑水平第一切割。 我们可以在怪物上方或下方进行切割，留下高度网格$a$或者$n-a+1$，同时宽度保持不变$m$。 我们采用较小的最终高度，因为最小化玩家选择更好的切割。 
2. 同样，考虑垂直第一切割。 这会产生一个大小的网格$n \times b$或者$n \times (m-b+1)$，我们再次保持较小的宽度。 
3.现在我们定义一个函数$f(x, y)$这代表减少所需的匝数$x \times y$矩形到$1 \times 1$当怪物总能重新调整到最佳位置时。 
4. 在一个回合中，玩家可以通过选择削减来减少任一维度，但对手确保最终的有效位置总是迫使最坏情况的未来减少。 这意味着每个维度在需要多少减半步骤方面表现独立。 
5. 因此，$f(x, y)$等于我们需要将两个维度都减少到 1 的次数，其中每次移动都尽可能减少一个维度，但只能将其分成两部分并保留较大的部分。 

实际上，每个维度的行为就像在切割后重复取较大的一半，这相当于在最坏的情况下重复除以 2。 

我们计算：

 -$f(x, y) = \lceil \log_2(x) \rceil + \lceil \log_2(y) \rceil$最后，我们评估所有四个第一步结果，并采取包括初始削减在内的最小总回合。 

### 为什么它有效

 第一次切割后，怪物总是可以重新定位到最糟糕的位置以进行未来的切割。 这消除了任何位置记忆，并将每个维度变成一个独立的收缩过程，其中每次切割最多减少该维度的一个二进制尺度级别。 由于切割每转只能分割一个轴，因此总转数累加了沿两个轴所需的减半步数。 初始位置仅影响第一次还原，此后该过程变得完全对称且与状态无关。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ceil_log2(x):
    # smallest k such that 2^k >= x
    k = 0
    v = 1
    while v < x:
        v <<= 1
        k += 1
    return k

def solve_case(n, m, a, b):
    # first cut horizontally
    h1 = min(a, n - a + 1)
    v1 = m

    # first cut vertically
    h2 = n
    v2 = min(b, m - b + 1)

    def f(x, y):
        return ceil_log2(x) + ceil_log2(y)

    # we already spend 1 turn on the first cut
    ans = 10**18

    ans = min(ans, 1 + f(h1, v1))
    ans = min(ans, 1 + f(h2, v2))

    return ans

t = int(input())
out = []
for _ in range(t):
    n, m, a, b = map(int, input().split())
    out.append(str(solve_case(n, m, a, b)))

print("\n".join(out))
```该实现明确地隔离了第一个动作，因为这是怪物位置唯一重要的点。 帮手`ceil_log2`计算一个维度达到 1 需要多少次减半，它直接模拟对抗性重新定位下最坏情况的贪婪分裂。 

功能`solve_case`评估第一次切割的两个可能的方向。 对于每个方向，它计算生成的矩形，然后添加完全缩小它的成本。 最终的答案是这两种可能性中的最小值。 

一个微妙的实现细节是我们从不显式模拟交替选择。 对手的最佳行为已经通过在对数模型中始终采用较大的结果段来编码，因此我们避免任何分支博弈树。

 ## 边缘情况

 一个$1 \times m$或者$n \times 1$网格立即消除一个自由度。 该算法可以正确处理这个问题，因为其中一个对数项变为零，并且第一次切割直接简化为单维问题。 

例如，$1 \times 8$与任何$b$产量：

 水平切割是不可能的，所以只能使用垂直切割，产生$1 \times 4$， 然后$1 \times 2$， 然后$1 \times 1$，转3圈。 该公式产生$\lceil \log_2 8 \rceil = 3$，完全匹配。 

当怪物在边界附近开始时，例如$(1, m)$，水平第一切割是高度不对称的，并且立即将高度降低到1，这可以大大降低未来的成本。 该算法通过采取捕获这一点$\min(a, n-a+1)$，确保始终选择切割的最佳一侧而不是假设对称。 

完全对称的中心起点，例如$(\frac{n}{2}, \frac{m}{2})$使两个首选项具有可比性。 该算法自然地评估两者并选择更好的一个，确保不依赖于任意的平局打破。
