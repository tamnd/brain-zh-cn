 ## 解决方案
 ## 问题理解

 给定一个以十进制形式表示的非常大的整数，对于每个这样的数字，我们需要计算有多少个不超过该数字的正整数仅由数字 4 和 7 组成。 

因此，任务不是在算术约束下构造数字，而是推理所有“幸运”数字字符串，直到给定的数字上限。 如果一个数字的每个数字都是 4 或 7，则该数字被认为是有效的，并且我们必须计算有多少个这样的有效数字位于从 1 到 n（含）的区间内。 

重要的困难来自于n的大小。 它最多可以有 100 位数字，因此它不适合任何内置整数类型。 任何解决方案都必须将其视为字符串并逐位推理。 测试用例的数量最多为 10^4，因此每个测试用例的效率必须与位数基本呈线性关系。 

生成长度不超过 100 的所有幸运数字的简单方法已经不可行。 即使限制长度，也有 2^100 个可能的幸运字符串，这是一个天文数字。 即使我们只生成与 n 相同长度的那些，我们仍然需要一种结构化的方法来有效地与 n 进行比较。 

一个微妙的边缘情况是当 n 本身包含 4 和 7 以外的数字时。例如，n = 500。正确答案是所有幸运数字 ≤ 500，而不仅仅是那些匹配数字模式 500 的数字。仅考虑 n 具有 4 或 7 的位置的粗心数字匹配方法会低估。 

另一个边缘情况是主导行为：单位数 n，例如 1、4 或 7。对于 n = 4，答案为 1；对于 n = 4，答案为 1；对于 n = 4，答案为 1。 对于 n = 3，答案为 0。任何数字 DP 都必须正确处理从“尚未构建数字”到“已开始数字”的转换。 

## 方法

 暴力破解的想法是按升序生成由数字 4 和 7 组成的所有数字，并计算 ≤ n 的数字。 我们可以通过递归构建长度达到|n|的所有字符串来做到这一点 并将每个与 n 作为字符串进行比较。 这在概念上是正确的，因为每个有效数字都被枚举一次，并且与 n 的比较很简单。 

然而，此类字符串的数量随着长度呈指数增长。 如果 n 有 100 位数字，则仅该长度就有 2^100 个可能的候选字符串。 即使当候选超过 n 时提前停止也无济于事，因为大多数候选是在我们知道它们太大之前生成的。 

关键的观察是我们永远不需要显式生成所有有效数字。 当解释为数字时，我们只需要计算有多少有效数字字符串按字典顺序小于或等于给定界限。 这是一个经典的数字动态编程设置：我们从最高有效数字到最低有效数字扫描数字，并在每个位置决定是匹配 n 的前缀还是严格变小。 

结构进一步简化，因为我们的数字集是固定的并且非常小，只有两位数字。 一旦我们不再严格限制 n，在每个位置，有效延续的数量纯粹是 2 的幂，与前缀值无关。 

我们将两部分结合起来。 首先，我们统计所有长度严格小于 len(n) 的幸运数字。 其次，我们使用紧前缀遍历来计算不超过 n 的相同长度的幸运数字。

 ## 算法演练

 我们将数字视为长度为 L 的字符串 s。 

### 步骤

1. 我们首先计算有多少个长度严格小于L的幸运数字。对于固定长度k，每个位置有2个选择：4或7。因此有2^k个这样的数字。 我们将 k 从 1 到 L-1 求和。 这会处理所有自动 ≤ n 的较小长度候选者。 
2. 然后，我们处理长度恰好为 L 的数字。我们从左到右扫描 s，维护一个状态，指示我们正在构建的前缀是否仍然完全等于 s 的前缀（严格条件），或者已经更小。 
3. 在每个位置 i，如果我们是紧的，我们将数字 s[i] 与允许的数字 4 和 7 进行比较。对于每个允许的数字 d：

 - 如果 d < s[i]，则剩余位置的任何完成都是有效的，贡献 2^(L-i-1)。 
- 如果 d == s[i]，我们继续采用紧模式。 
- 如果 d > s[i]，我们跳过，因为它会超出前缀约束。 
4. 如果在任何位置 4 和 7 都不等于或小于 s[i]，我们会提前中断，因为没有有效的数字可以再与前缀匹配。 
5. 我们将所有捐款以 998244353 为模进行累加。 

### 为什么它有效

 该算法保持前缀约束不变：在步骤 i，我们只计算前 i 位形成前缀的数字，该前缀按字典顺序小于或等于 n 的前缀。 一旦我们选择了比n中相应数字小的数字，剩下的后缀就完全自由了，因为4和7的任何组合仍然会保持小于n的数字。 这将问题从全局比较减少到使用 2 的幂进行独立后缀计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    pow2 = [1] * 105  # enough for length up to 100
    for i in range(1, 105):
        pow2[i] = (pow2[i - 1] * 2) % MOD

    for _ in range(t):
        s = input().strip()
        L = len(s)

        # count all lucky numbers with length < L
        ans = 0
        for k in range(1, L):
            ans = (ans + pow2[k]) % MOD

        # count same-length numbers
        tight = True

        for i in range(L):
            cur = int(s[i])
            for d in (4, 7):
                if d < cur:
                    ans = (ans + pow2[L - i - 1]) % MOD
                elif d == cur:
                    # continue tight only if valid prefix
                    break
            else:
                # if neither 4 nor 7 matched, no tight continuation possible
                tight = False
                break

            if cur not in (4, 7):
                # once prefix mismatch occurs, we stop tight propagation
                pass

        # check if n itself is lucky
        ok = all(c in '47' for c in s)
        if ok:
            ans = (ans + 1) % MOD

        print(ans % MOD)

if __name__ == "__main__":
    solve()
```第一个循环预先计算 2 的幂，因为每个自由后缀位置都会贡献两个独立的选择。 第一个求和将所有短于 n 的有效幸运数字相加。 

第二部分尝试扩展前缀匹配。 内部逻辑使用与数字 4 和 7 的比较来决定何时可以分支到更小的前缀。 如果所选数字严格小于 s[i]，则其余后缀完全免费，提供 2 的幂贡献。 

最后，我们显式检查 n 本身是否是一个幸运数字，因为计数逻辑在分支时仅考虑严格较小的前缀。 

一个微妙的实现细节是，我们必须预先计算 2 到 100 的幂，因为后缀长度取决于剩余位置。 此外，字符串比较优于整数解析，因为 n 可能非常大。

 ## 边缘情况

 一个棘手的情况是，当 n 包含字符串中 {4, 7} 之外的数字时，例如 n = 500。该算法可以正确处理此问题，因为一旦我们到达小于 n 中相应数字的数字，我们就会立即通过 2 的幂贡献添加所有后缀组合，而不需要后面的数字。 

对于 n = 500，在第一个数字处，我们将 4 和 7 与 5 进行比较。数字 4 较小，因此我们将长度为 2 的所有补全相加，即 2^2 = 4。数字 7 较大，没有任何贡献。 然后我们继续扫描，但没有紧密的连续正确地存在，并且我们不会过度计数，因为所有剩余的数字已经在分支步骤中考虑在内。 

另一个边缘情况是 n 本身是有效的幸运数字，例如 744。算法必须在末尾显式添加 +1。 如果没有这个，计数将只包括严格小于 n 的数字，从而缺少边界解。
