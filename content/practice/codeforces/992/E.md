 ## 解决方案

 ## 问题理解

 我们得到了一系列代表萨满的值，按时间排序。 每个职位都拥有“权力”，我们不断更新单个职位。 每次更新后都要判断是否存在索引$j$使得值在$j$严格等于之前所有值的总和$j$。 如果存在这样的索引，我们输出其中任何一个，否则输出-1。 

以更可操作的方式重新表述，我们在点更新下维护一个数组，并反复询问是否有任何前缀边界分割数组，以便右端点等于前缀和。 

约束条件达到$2 \cdot 10^5$元素和$2 \cdot 10^5$更新，因此重新计算每个查询的前缀和已经是临界点，但仍然可行。 真正的困难在于，在最坏的情况下，检查每个查询的每个位置将是二次的，这太慢了。 我们需要一个允许快速范围求和查询的结构，以及某种方法来定位有效索引，而无需在每次更新后扫描所有位置。 

当所有值都很小或为零时，会出现微妙的边缘情况。 在这种情况下，许多索引简单或部分地满足条件，并且仅检查一个候选者（例如扫描前缀后的最后一个元素或第一个匹配项）的简单方法很容易错过数组中其他位置的有效答案。 另一个边缘情况是重复更新翻转值以使有效索引在数组中移动，这会破坏任何静态预计算方法。 

## 方法

 暴力策略很简单：每次更新后，从左到右计算前缀和并检查是否有任何位置$j$满足$a_j = \sum_{i<j} a_i$。 每次查询都会花费$O(n)$, 给予$O(nq)$总操作。 和$n, q \le 2 \cdot 10^5$，这达到了$4 \cdot 10^{10}$操作，这远远超出了任何可行的限制。 

关键的观察是，我们不需要从头开始重新计算所有内容，只需维护前缀和并有效地查询它们。 条件$a_j = \text{prefixSum}(j-1)$可以重写为：$$\text{prefixSum}(j) = 2 \cdot \text{prefixSum}(j-1)$$这仍然没有直接简化搜索，但它表明问题与前缀和结构紧密相关。 

更直接的方法是维护前缀和的 Fenwick 树（或线段树），然后使用可以快速找到条件成立的索引的第二种结构。 技巧是在派生数组上维护一个线段树，其中每个位置存储：$$f[i] = a[i] - \text{prefixSum}(i-1)$$那么一个有效的国王萨满正是一个索引，其中$f[i] = 0$。 问题是前缀和取决于更新，所以$f[i]$不独立。 相反，我们维护两棵线段树：一棵用于数组本身（用于计算前缀和），一棵使用前缀和引导的索引搜索进行隐式检查。 

标准预期解决方案避免显式维护$f[i]$。 相反，我们观察到对于候选索引$i$，我们可以计算它的前缀和$O(\log n)$，这样我们就可以快速测试有效性。 问题简化为查找单调谓词在树上成立的任何索引，这建议使用检查函数对线段树进行二分搜索。 

我们构建一个存储总和的线段树，然后执行递归搜索：在表示线段的节点处$[l, r]$，我们计算左半部分的总和并将其与潜在的候选位置进行比较。 关键思想是，如果我们在遍历过程中动态维护前缀和，我们就可以决定左子节点或右子节点中是否存在有效索引。 

这导致树下降，在每个节点上，我们维护当前段左侧所有内容的总和，使我们能够有效地检查中点的条件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(nq)$|$O(n)$| 太慢了 |
 | 带引导搜索的线段树 |$O(q \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们使用线段树来存储数组的和。 

1. 在初始数组上构建线段树，以便可以在对数时间内查询任何范围和。 这是必要的，因为每个有效性检查都依赖于前缀和。 
2.对于位置的每次更新$p$，用新值更新该位置对应的线段树节点$x$。 这可确保所有未来的前缀总和反映更改。 
3. 每次更新后，尝试使用线段树上的递归搜索来查找有效索引。 我们维护一个运行的前缀和，称为`left_sum`，最初为零，表示严格位于当前段之前的元素之和。 
4. 在节点覆盖线段处$[l, r]$，计算左孩子的总和。 如果我们充分挖掘的话，这代表了左半部分的贡献。 我们通过检查是否存在条件可以满足的某个位置来测试左子元素中是否存在有效索引，给定`left_sum`。 
5. 如果左子节点可能包含有效索引，我们首先下降到它，携带`left_sum`不变。 否则，我们更新`left_sum`通过添加整个左子项总和并移动到右子项。 
6. 当我们到达位置处的叶子时$i$，我们检查是否`left_sum == a[i]`。 如果是这样，我们返回$i$作为一个有效的国王萨满。 
7. 如果遍历过程中没有叶子满足条件，则返回-1。 

搜索之所以有效，是因为在每个决策点，我们保留了与段边界相对应的精确前缀和，因此叶子检查相当于原始定义。 

### 为什么它有效

 在递归的任意一点上，`left_sum`等于原始数组顺序中严格位于当前段之前的所有元素的总和。 这个不变量保证了当我们到达索引时$i$,`left_sum`正是$\sum_{j<i} a[j]$。 叶子条件直接匹配问题要求，因此任何返回的索引都是有效的。 相反，如果存在有效索引，则引导下降永远不会丢弃包含该索引的分支，因为每个节点的决策都保留了基于精确前缀分区的可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, v, l, r, arr):
        if l == r:
            self.t[v] = arr[l]
        else:
            m = (l + r) // 2
            self.build(v * 2, l, m, arr)
            self.build(v * 2 + 1, m + 1, r, arr)
            self.t[v] = self.t[v * 2] + self.t[v * 2 + 1]

    def update(self, v, l, r, pos, val):
        if l == r:
            self.t[v] = val
        else:
            m = (l + r) // 2
            if pos <= m:
                self.update(v * 2, l, m, pos, val)
            else:
                self.update(v * 2 + 1, m + 1, r, pos, val)
            self.t[v] = self.t[v * 2] + self.t[v * 2 + 1]

    def find(self, v, l, r, left_sum):
        if l == r:
            return l if self.t[v] == left_sum else -1

        m = (l + r) // 2
        left_sum_left = left_sum

        if self.t[v * 2] >= 0:
            res = self.find(v * 2, l, m, left_sum_left)
            if res != -1:
                return res

        left_sum_right = left_sum + self.t[v * 2]
        return self.find(v * 2 + 1, m + 1, r, left_sum_right)

    def query_answer(self):
        return self.find(1, 0, self.n - 1, 0)

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    st = SegTree(a)

    for _ in range(q):
        p, x = map(int, input().split())
        st.update(1, 0, n - 1, p - 1, x)
        ans = st.query_answer()
        print(ans + 1 if ans != -1 else -1)

if __name__ == "__main__":
    solve()
```线段树存储和，以便在遍历期间可以重建前缀推理。 每次修改后更新操作都会保持正确性。 

搜索函数是一种受控下降，它隐式地重建前缀和，而不是从头开始重新计算它们。 

一个微妙的点是，索引内部是从 0 开始的，但输出是从 1 开始的，因此在成功搜索后需要进行最终调整。

 ## 边缘情况

 大小为 1 的最小数组测试算法是否正确地将空前缀和视为零。 如果更新后单个值变为零，则必须接受索引。 

完全一致的数组强调多个索引可以满足条件，并且算法不得假设唯一性。 

不存在前缀相等的情况，例如`[1, 2, 4]`，确保搜索正确耗尽线段树的两个分支，而不会错误地报告匹配。 

最后的边缘情况是当更新在数组中移动有效索引时。 由于每次更新后都会重新计算搜索，因此过时的假设不得在查询中持续存在。
