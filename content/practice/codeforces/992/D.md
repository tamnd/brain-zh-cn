 ## 解决方案

 ## 问题理解

 我们得到一个正整数序列。 根据这个序列，我们考虑每个连续的块并为其计算两个值：元素之和和元素乘积。 如果子数组的乘积与其和之间的比率正好是一个固定常数，则该子数组被认为是有效的$k$， 意义$\frac{P}{S} = k$，或等价地$P = k \cdot S$。 

任务是计算有多少子数组满足这个等式。 

这些约束足够严格，任何子数组的二次枚举都不太可能通过。 和$n$最多$2 \cdot 10^5$,天真的$O(n^2)$扫描已经给出了关于$2 \cdot 10^{10}$最坏情况下的子数组，即使每个子数组不断工作也会太慢。 这立即迫使我们避免为每个段独立地重新计算乘积和总和。 

方程中隐藏着更深层次的结构约束$P = kS$。 即使是中等长度细分市场的产品也会增长得非常快，因为所有$a_i \ge 1$。 这表明大多数长子数组将溢出或超过线性范围$kS$，仅随段长度线性增长。 

当值为 1 或小整数时，会出现微妙的边缘情况。 

例如，如果数组全为 1 并且$k = 1$，每个子数组都满足条件，因为乘积和总和都等于长度。 假设产品“增长太快”的幼稚实现可能会错误地修剪此类情况。 

另一个边缘情况是当$k$很大。 如果$k$接近于$10^5$，即使很短的段也可能无法相等，因为乘积以乘法增长，因此只有非常小的子数组可以匹配。 

关键的困难在于乘积是乘法，而和是加法，这使得直接两指针推理在不利用增长约束的情况下变得不平凡。 

## 方法

 暴力方法很简单：枚举每个子数组，计算其和和乘积，并检查是否$P = kS$。 这是正确的，但重新计算每个子数组的两个值的成本很高。 即使有总和的前缀和，该产品仍然需要$O(\text{length})$每个子数组的更新，导致$O(n^2)$或更糟糕的行为。 在最坏的情况下，这会变成数百亿次乘法。 

主要观察是我们不需要考虑长子数组。 一旦产品超过$k \cdot S$，扩展子数组仅以乘法方式增加乘积，而右侧仅线性增长。 因为所有元素都至少为 1，所以乘积的增长速度至少与长度一样快，并且当任何元素超过 1 时通常会快得多。 

这意味着有效段必须很短。 事实上，我们可以证明，每当产品超过与以下相关的可管理阈值时$k$，进一步扩展不能恢复平等。 这使我们能够将注意力限制在从每个索引开始的子数组上，并且仅扩展有限数量的步骤（由于整数的指数增长，大约几十或最多大约 60-70）。 

这将问题转化为从每个起点开始的有界扩展。 对于每个索引$i$，我们扩展$j$在保持运行总和和乘积的同时前进，当乘积变得太大而无法相等时提前停止$kS$。 我们即时计算匹配数。 

这是有效的，因为乘积的指数增长主导了总和的任何线性增长，确保每个索引的搜索空间保持较小。

 ## 算法演练

 ### 关键思想

 我们修复左端点并向右扩展，但一旦乘积相对于可能匹配的值变得太大，就提前停止$k \cdot \text{sum}$。 

### 步骤

 1. 迭代每个索引$i$作为子数组的潜在起点。

 这确保了每个有效子数组的左边界仅被考虑一次。
 2.初始化两个变量：`prod = 1`和`s = 0`。 

这些存储当前段的乘积和总和$[i, j]$。 
3. 对于每个$i$， 延长$j$从$i$前进同时$j$保持在有限的范围内。 

我们提前停止，如果`prod`超过安全界限（例如，大于$k \cdot s$乘以边距，或者只是当它超过一个大的截止值时），因为进一步的乘法永远不会减少它。 
4. 在每一步中，更新：$$s \mathrel{+}= a[j], \quad prod \mathrel{*}= a[j]$$5.更新后，检查是否`prod == k * s`。 

如果为真，则增加答案。 
6. 如果`prod`变得太大（例如超过$k \cdot s$大幅度或超过$10^{18}$)，为此打破循环$i$。 

这种修剪是安全的，因为任何进一步的乘法只会增加乘积，而目标会线性增长。 

### 为什么它有效

 正确性来自于乘积的单调增长。 一旦我们确定了起始索引，扩展段只会增加总和和乘积，但乘积会成倍增长。 如果在某个时刻该产品已经主导了任何可能的价值$k \cdot s$，任何扩展都无法恢复平等。 因此，所有有效匹配必须出现在该截止点之前，并且每个有效子数组在其端点处仅检查一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    ans = 0
    
    for i in range(n):
        s = 0
        prod = 1
        
        for j in range(i, n):
            s += a[j]
            prod *= a[j]
            
            if prod == k * s:
                ans += 1
            
            if prod > k * s and a[j] > 1:
                break
            if prod > 10**18:
                break
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案为每个起始索引保留运行总和和乘积。 乘积以乘法更新，而总和以加法更新。 支票`prod == k * s`直接对问题的条件进行编码。 

早期停止条件至关重要。 如果当前元素大于1并且乘积已经超过目标，进一步相乘只能增加差距，因此继续是没有意义的。 硬顶$10^{18}$防止类似溢出的行为，并在 Python 的任意精度算术下保持计算安全。

 ## 边缘情况

 一个关键的边缘情况是当所有元素都为 1 并且$k = 1$。 在这种情况下，乘积和总和始终等于段长度。 该算法自然地处理这个问题，因为总和和乘积都不会增长得更快，因此没有早期中断触发，并且每个段都会被计算在内。 

当大量数字提前出现时，就会出现另一种边缘情况。 例如，输入：```
3 1
100 2 3
```在$i = 0$，产品立即变为 100，而$k \cdot sum = 100$，所以第一个元素被计算在内。 此后，任何扩展都会产生远远大于总和线性增长的乘积，从而触发提前终止。 

最后，小值后跟大尖峰确保修剪的正确性。 一旦产品超出任何合理范围$k \cdot sum$，从同一索引开始的未来段无法恢复相等，因此提前中断不会跳过有效答案。
