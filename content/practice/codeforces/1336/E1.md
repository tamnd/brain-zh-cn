 ## 解决方案

 ## 问题理解

 我们得到一个整数集合，每个整数都编码为 m 位掩码。 从这些数字中，我们可以选择它们的任何子集，包括空子集，并且对于每个子集，我们计算所有选定值的异或。 然后，该异或结果被解释为二进制，我们将其“值”测量为该二进制表示中设置的位数。 

任务不是计算单个子集，而是考虑所有$2^n$子集并计算有多少子集产生一个 XOR，其 popcount 恰好是$i$，对于每一个$i$从$0$到$m$。 

关键结构是子集选择通过 XOR 进行交互，这在 GF(2) 上是线性的。 最终 XOR 的每一位仅取决于有多少个选定元素设置了该位的奇偶校验。 

这些约束使得对子集进行暴力破解是不可能的。 和$n \le 2 \cdot 10^5$，枚举所有子集是指数级的。 即使为子集生成 XOR 值也需要$O(2^n \cdot n)$，这远远超出了可行的限度。 

重要的结构提示是$m \le 35$，这意味着这些值位于 GF(2) 上相对低维的向量空间中。 这表明子集 XOR 空间具有很强的线性代数结构，并且子集计数应该减少到对基向量而不是单个元素的推理。 

当所有数字都为零时，会出现微妙的边缘情况。 每个子集都会产生异或零，因此答案完全集中在值上$0$。 另一个极端情况是数字独立跨越所有维度； 那么异或就均匀分布在子空间上，并且对子集大小的朴素频率推理完全失败，因为子集在位之间不独立。 

最后一个陷阱是假设位之间是独立的。 虽然 XOR 按位运算，但子集耦合意味着位在分布上并不独立，除非仔细处理基础。 

## 方法

 直接方法枚举所有子集、计算 XOR 并计算 popcount。 这是正确的，因为它完全遵循定义。 然而，它需要迭代$2^n$子集，每个子​​集占用$O(n)$XOR 工作，导致不可能的运行时间。 

更结构化的观点是从子集转向 XOR 的线性代数。 每个数字都是一个向量$\mathbb{F}_2^m$。 所有子集 XOR 的集合形成由这些向量生成的线性子空间。 这个空间的维度就是秩$r$系统的。 

一旦我们有了基础，每个子集 XOR 就对应于为基础向量选择系数，而相关向量仅乘以计数而不改变可达的 XOR 空间。 这将问题转化为计算我们可以实现跨度中每个异或向量的有多少种方式，然后通过 popcount 对结果进行分组。 

关键的观察结果是，子集结构分解为两部分：确定 XOR 空间的自由选择，以及仅将每个配置乘以的冗余元素$2^{n-r}$。 将数组缩减为基础后，我们最多只需要处理$r \le m \le 35$向量，使得掩模上的指数 DP 变得可行。 

然后，我们在基向量上执行 DP：每个基向量要么对 XOR 有贡献，要么没有贡献，从而有效地构建所有$2^r$可能的异或结果。 每个结果对应于基本元素的一个子集，我们计算每个 popcount 产生的数量。 最后我们乘以$2^{n-r}$考虑依赖元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n 2^n)$|$O(1)$| 太慢了|
 | 线性基+子集DP |$O(m 2^m)$|$O(2^m)$| 已接受 |

 ## 算法演练

 我们将每个数字视为一个位向量，并在 GF(2) 上构建线性基。 

1. 根据输入数组构建线性基。 我们通过使用先前存储的基本向量贪婪地消除最高设置位来插入每个数字。 这确保了每个基向量都有一个唯一的主元位，因此基保持独立。 
2. 计算有多少输入数字与基数线性相关。 如果我们插入一个在消除后减少到零的数字，它不会增加排名并有助于稍后的乘法因子。 
3.设等级为$r$。 我们现在有$r$生成所有可能的 XOR 结果的独立向量。 
4.初始化DP数组，其中dp[x]表示XOR等于x的基向量子集的数量。 从 dp[0] = 1 开始，表示空子集。 
5. 对每个基向量进行一一处理。 对于每个向量 v，通过合并两种情况来更新 dp：不采用 v（保持 XOR 不变）和采用 v（通过 v 进行 XOR 切换）。 这是 XOR 空间上的标准子集卷积。 
6. 处理完所有基向量后，dp 包含在基空间中实现每个 XOR 值的方式的计数。 
7. 对于每个 XOR 值，计算其 popcount 并将 dp[value] 添加到相应的答案存储桶中。 
8. 将每个桶乘以$2^{n-r}$，因为每个相关向量可以自由包含或排除，而不影响 XOR 空间。 

### 为什么它有效

 线性基础确保原始集合中的每个 XOR 结果唯一对应于基础向量的子集以及相关向量中的任意选择。 这创建了一个乘积结构：可到达的 XOR 空间是$r$GF(2) 上的维向量空间，并且该空间中的每个点都可以精确地到达$2^{n-r}$子集。 DP 对每个点精确地枚举向量空间一次，最终的乘法将恢复完整的子集计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    basis = [0] * m
    rank = 0

    for x in a:
        v = x
        for i in reversed(range(m)):
            if (v >> i) & 1:
                if basis[i]:
                    v ^= basis[i]
                else:
                    basis[i] = v
                    rank += 1
                    break

    vecs = []
    for i in range(m):
        if basis[i]:
            vecs.append(basis[i])

    dp = [0] * (1 << len(vecs))
    dp[0] = 1

    for v in vecs:
        for mask in range((1 << len(vecs)) - 1, -1, -1):
            dp[mask ^ v] = (dp[mask ^ v] + dp[mask]) % MOD

    pow2 = pow(2, n - rank, MOD)

    ans = [0] * (m + 1)
    for mask in range(1 << len(vecs)):
        pc = mask.bit_count()
        ans[pc] = (ans[pc] + dp[mask]) % MOD

    for i in range(m + 1):
        ans[i] = ans[i] * pow2 % MOD

    print(*ans)

if __name__ == "__main__":
    solve()
```实现首先构建 XOR 线性基。 每个数字都会根据现有的主元进行减少，以便我们只保留独立的向量。 等级决定了剩余的自由度。 

然后 DP 枚举基向量的所有 XOR 组合。 掩码循环中的反向迭代需要避免在同一步骤中重复使用更新的状态，从而保持子集转换的正确性。 

最后，每个可到达的 XOR 都根据有多少原始子集由于依赖元素而塌陷到其中进行加权，通过乘以处理$2^{n-r}$。 

## 工作示例

 ### 示例 1

 输入：```
4 4
3 5 8 14
```基础构建后，假设我们获得 4 个独立向量（秩 4）。 DP空间有大小$2^4 = 16$。 每个子集唯一对应一个 XOR 掩码。 

| 步骤| 活性载体| dp 尺寸 | 解读|
 | ---| ---| ---| ---|
 | 开始 | 无 | 1 个州 | 仅异或 0 |
 | v1 之后 | {v1} | 2 个州 | 0，v1 |
 | v2 之后 | {v1，v2} | 4 个州 | 全跨度|
 | v3 之后 | {v1,v2,v3} | 8 个州 | 扩大空间|
 | v4 之后 | 全部 | 16 个州 | 完整的异或空间|

 然后，我们按 popcount 和输出计数对这 16 个 XOR 值进行分组。 

这表明，一旦基跨越空间，DP 就会针对每个基子集完全枚举所有 XOR 结果一次。 

### 示例 2

 输入：```
3 3
0 0 0
```所有向量均为零，因此基为空且秩为 0。DP 仅包含 dp[0] = 1。然而，原始元素的每个子集都是不同的，给出$2^3 = 8$方式，所有产生 XOR = 0。 

| 步骤| 基本尺寸| DP | 缩放 |
 | ---| ---| ---| ---|
 | 建造| 0 | {0:1} | 全部依赖|
 | 决赛| 0 | 不变| 乘以 8 |

 输出变为：```
8 0 0 0
```这证实了相关向量的作用：它们不会改变 XOR 结构，但会乘以计数。

 ## 边缘情况

 一种重要的边缘情况是所有元素都为零。 基为空且秩为零，但每个子集仍然存在。 该算法正确地产生 dp[0] = 1，然后乘以$2^n$，产生 popcount 0 处的所有质量。 

另一种情况是输入已经形成完整的基础。 这里的rank等于m或更小，并且不发生相关缩放。 仅 DP 就可以完全确定答案，并且不应用额外的乘法因子，这可以防止计数过多。 

第三种情况是多个元素简化为相同的基向量。 贪婪插入确保每个枢轴位仅存储一个代表，从而防止 DP 中的重复状态转换并避免超出范围的指数爆炸$2^m$。
