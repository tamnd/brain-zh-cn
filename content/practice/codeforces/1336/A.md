 ## 解决方案

 ## 问题理解

 给定一棵以城市 1 为根的树。每个城市要么被选为工业城市，要么被选为旅游城市，具体情况如下：$k$被选为工业城市。 

每个工业城市都会派一名使者到首都。 该特使沿着树中唯一的最短路径从其城市到达节点 1。沿着这条路径，特使每经过一个旅游城市，就会获得 1 单位的幸福感。 工业城市并不能贡献幸福。 

因此，总分是所有选定的产业节点中严格位于根路径上的旅游节点数量的总和。 

我们想选择哪个$k$节点变得工业化以最大化这个总和。 

这棵树最多可以有$2 \cdot 10^5$节点，因此任何尝试所有大小子集的解决方案$k$是不可能的。 甚至$O(n^2)$或者$O(nk)$在最坏的情况下，样式遍历将会失败。 我们周围需要一些东西$O(n \log n)$或者$O(n)$。 

一个关键的结构点是，每个节点的贡献取决于它到根的距离以及树中位于其上方的选定工业节点的数量。 这种依赖性表明我们应该根据深度和子树结构来思考，而不是显式的路径枚举。 

天真的方法会尝试所有方法来选择$k$节点并计算分数，但这是组合的$\binom{n}{k}$，立即不可行。 

另一个微妙的失败案例是贪婪地选择最深的节点而不考虑路径的重叠。 如果两个选定的节点共享到根的长前缀路径，则它们的贡献不是独立的，并且天真的仅深度选择可能会夸大收益或错过更好的配置。 

## 方法

 直接的暴力方法将枚举每个子集$k$节点并通过遍历每个选定节点的路径到根来计算总幸福度。 每次评估费用$O(n)$，因为路径可以很长$O(n)$在一个链条中。 这导致$O(n \binom{n}{k})$，这是一个天文数字。 

为了简化，我们需要了解每个节点在结构上的贡献。 如果一个节点$v$被选为工业，它为根路径上的每个旅游节点贡献 1 个单位的幸福感。 这相当于统计到根的路径上所有未被选中的节点。 

我们以不同的方式重写这个想法。 考虑每个节点$v$。 设其深度为$d(v)$。 如果我们选择$v$作为工业，当它的大部分祖先仍然是旅游业时，它的潜在贡献就会最大化。 然而，祖先可能在多个选定的节点之间共享，因此直接计算每个节点的贡献是很混乱的。 

更清晰的视角是把问题倒过来。 我们不用对工业节点进行求和，而是可以考虑每个节点对总分的贡献有多少，具体取决于有多少个选定的节点通过它。 每个节点$u$为其子树中的每个工业节点（包括其自身）贡献 1 的答案，除非路径作为工业通过它，这会阻止贡献。 

这表明我们应该优先考虑其选择“影响”许多祖先的节点。 节点越深，其到根的路径上的其他节点就越少，因此选择较深的节点往往会产生更高的贡献。 

关键的见解是计算每个节点的深度以及其子树中有多少个节点。 然后，我们定义一个值，表示使该节点工业化的好处：具体来说，树中较深的节点往往会在其路径上产生更多的旅游节点。 

我们对每个节点进行计算：

 从根部开始的深度，以及

 其子树的大小。 

选择节点的有效增益与其深度密切相关，因为每个选定的节点大致贡献其深度减去重叠的调整。 正确的贪心策略出现：选择$k$具有最大值的节点$depth - subtree\_impact$，它简化了通过从 DFS 排序得出的计算“利润”对节点进行排序。 

一个标准且更精确的公式是计算每个节点的深度以及位于到选定节点的路径上的子节点的数量，这导致了已知的简化：按深度排序节点减去后代影响的数量，这减少为按深度排序并在 DFS 之后贪婪地选择。 

在实践中，可接受的简化是：为每个节点计算一个值，该值等于其深度减去其沿 DFS 排序的子树大小贡献，然后选择顶部$k$。 

这是有效的，因为节点的贡献正是它在选定路径上被用作旅游节点的次数，并且通过优先考虑树中较深且重叠较少的节点来最大化该贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（子集枚举）|$O(n \cdot \binom{n}{k})$|$O(n)$| 太慢了|
 | DFS + 按深度贡献排序 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 以节点 1 为树的根，并使用 DFS 计算每个节点的深度。 

深度表示在通往首都的路径上的节点上方有多少个潜在的旅游城市。 
2. 在DFS期间，还计算每个子树的大小。 

这有助于捕获一个节点“下方”有多少个节点，从而了解选择决策如何向下传播。 
3.对于每个节点$v$，计算一个值$gain(v)$定义为：

 受益于选择的节点数量$v$，可以推导为$depth(v) - (subtree\_size(v) - 1)$。 

这反映出更深的节点提供更多的旅游贡献，而大型子树由于共享路径而减少边际效益。 
4. 对所有节点进行排序$gain(v)$按降序排列。 
5.选择顶部$k$节点。 这些是最佳的工业城市。 
6. 通过对所选节点的深度求和并减去由增益公式隐式处理的重叠校正来计算最终答案。 

### 为什么它有效

 每个节点通过从选定节点到根的路径上有多少个旅游节点对最终得分做出贡献。 DFS 将这些路径分解为独立的子树贡献。 增益函数将重叠的路径贡献转换为附加的独立权重。 由于子树聚合完全捕获了每个重叠，因此选择具有最高边际增益的节点可确保全局最优累积，而不会重复计算或错过交互。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, k = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

depth = [0] * (n + 1)
parent = [0] * (n + 1)
order = []

def dfs(u, p):
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        parent[v] = u
        dfs(v, u)
    order.append(u)

dfs(1, 0)

sub = [1] * (n + 1)
for u in order:
    for v in g[u]:
        if v == parent[u]:
            continue
        sub[u] += sub[v]

gain = []
for i in range(1, n + 1):
    gain.append(depth[i] - (sub[i] - 1))

gain.sort(reverse=True)
print(sum(gain[:k]))
```DFS 构建深度和后序列表。 深度直接编码距根的距离，根是每条路径的基础贡献结构。 随后使用反向 DFS 顺序计算子树大小，以便每个节点聚合其子节点。 

增益定义将深度和子树重叠之间的交互压缩为单个可排序度量。 排序确保我们总是选择对总幸福感具有最强边际效应的节点。 总结顶部$k$Gains 给出了最终的最优值，无需模拟 Envoy 路径。 

一个微妙的实现细节是，必须在知道 DFS 遍历顺序后计算子树大小。 另一个是确保增加递归深度，否则链形树会溢出 Python 的递归堆栈。

 ## 边缘情况

 链状树显示了深度如何占主导地位。 在`1-2-3-4-5`，选择两个最深的节点会产生与深度一致的增益，并且该算法由于其较大的增益值而正确地将较深的节点排名较高。 

星形树表明所有叶子都是等效的。 每个叶子的深度为 1，子树大小为 1，因此所有增益都是相同的，并且任何选择$k$leaves 产生相同的结果，排序自然会处理该结果。 

高度不平衡的树表明子树大小惩罚很重要。 根附近的节点具有较大的子树大小，从而减少了增益，从而防止它们被错误地选择为提供更独立旅游路径的更深节点。
