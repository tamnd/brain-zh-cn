 ## 解决方案

 ## 问题理解

 我们得到一个整数集合，每个整数代表一个“娃娃”，其中每个值都已经以二进制编码并适合`m`位。 从这些娃娃中，我们考虑了每一个可能的子集。 对于每个子集，我们计算所有选定值的异或，然后查看有多少个`1`位出现在该异或结果中。 

每个子集都会贡献一个结果：其 XOR 值，并且该子集的“分数”是该 XOR 中设置的位数。 任务是计算每个可能的分数`0`到`m`，有多少个子集与恰好那么多的子集产生异或`1`位。 

输入大小使得对子集的暴力破解变得不可能。 和`n`最多`2e5`，子集的数量是`2^n`，这是一个天文数字。 甚至迭代值也是不可能的。 唯一可用的结构是 XOR 在位上是线性的，因此位在非常强的代数意义上独立运行。 

当许多元素为零或所有元素都相同时，会出现微妙的边缘情况。 例如，如果所有`a_i = 0`，每个子集异或为零，所以只得分`0`非零且等于`2^n`。 尝试枚举每个子集的 XOR 值的简单实现将会超时或无法正确聚合。 另一个极端情况是当`n = 1`，其中答案简单地分为选择或不选择单个元素。 

真正的困难在于 XOR 跨元素耦合选择，但仅限于每个位位置内。 这表明对位向量空间进行变换，而不是直接对子集进行变换。 

## 方法

 直接的方法是枚举所有子集，计算 XOR，然后计算位数。 这需要迭代`2^n`状态，这是不可能的。 即使通过跟踪 XOR 频率进行改进仍然会让我们陷入困境，因为 XOR 空间有大小`2^m`，这是可以管理的，但是计算子集 XOR 的分布仍然需要组合`n`高维卷积中的向量。 

关键的结构见解是每个元素独立地对 XOR 的每一位做出贡献，但子集形成引入了依赖关系，可以使用 XOR 空间上的变换来线性化这些依赖关系。 我们不考虑子集，而是考虑所有可能的 XOR 结果的分布。 

让`F[x]`是 XOR 等于的子集的数量`x`。 那么我们想要的答案就是分组`F[x]`的流行计数`x`。 子集卷积定义`F`XOR 是一种经典的 Walsh-Hadamard 变换情况：每个元素贡献一个多项式`(1 + z^{a_i})`在 XOR 卷积代数中。 

这导致了一个标准技巧：在 XOR 空间上应用快速沃尔什-哈达玛变换 (FWHT)。 我们初始化一个频率数组，其中`F[0] = 1`（空子集）并通过乘法更新变换域来迭代“卷积”每个元素。 在 FWHT 空间中，异或卷积变为逐点乘法，因此每个元素以结构化方式将某些组件加倍。 处理完所有元素后，我们进行逆变换来恢复`F[x]`。 

最后，我们计算`popcount(x)`对于每个`x`并积累。 

关键思想是子集 XOR 分布不是通过子集枚举构建的，而是通过重复 XOR 卷积构建的，在 FWHT 下对角化。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对子集的暴力破解 | O(2^n·m) | O(2^n·m) | O(1) | O(1) | 太慢了|
 | XOR 空间上的 FWHT | O(m·2^m + n·2^m) 或优化 O(n + m·2^m) | O(2^m) | O(2^m) | 已接受 |

 ## 算法演练

 我们在维度的异或向量空间中工作`m`，其中包含`2^m`可能的异或值。 

### 1. 构建初始多项式

 我们从频率数组开始`F`尺寸的`2^m`， 在哪里`F[0] = 1`。 这代表空子集。 

这是 XOR 卷积的单位元素：不选择任何元素会产生 XOR 零。 

### 2. 应用 FWHT 准备

 我们在概念上想要计算：```
F_final = ∏ (1 + δ_{a_i})
```在异或卷积下。 我们不直接执行卷积，而是进行变换`F`进入 FWHT 空间，其中 XOR 卷积变成逐点乘法。 

### 3. 正向 FWHT 变换

 我们将 FWHT 应用于当前数组表示。 这以与 XOR 子空间结构一致的方式混合 XOR 状态之间的值。 

经过这一步，子集卷积就变成了乘法。 

### 4. 乘以每个元素的贡献

 每个元素`a_i`贡献一个因素`(1 + x[a_i])`在变换空间中。 在实践中，我们维护一个变换数组并迭代更新它，以便每个索引反映元素的包含或排除。 

此步骤对组合选择“接受或跳过每个娃娃”进行编码，而无需显式枚举子集。 

### 5.逆FWHT

 我们应用逆 FWHT 从变换空间返回到实际的 XOR 频率`F[x]`，其中每个`F[x]`计算有多少子集产生 XOR 等于`x`。 

### 6. 按 popcount 聚合

 对于每个异或值`x`，我们计算`popcount(x)`并添加`F[x]`到相应的答案桶。 

这会将 XOR 值的分布转换为设置位数的分布。 

### 为什么它有效

 关键的不变量是，在处理每个元素之后，变换空间表示在 XOR 卷积下精确地编码子集多项式。 FWHT 对异或卷积进行对角化，因此子集构造变成了独立坐标上的乘法。 每个子集都唯一对应于包含或排除每个元素的选择的乘积，并且 FWHT 确保这些选择在所有 XOR 状态上正确累积，而不会在状态之间产生干扰。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def fwht(a, invert):
    n = len(a)
    step = 1
    while step < n:
        jump = step << 1
        for i in range(0, n, jump):
            for j in range(step):
                u = a[i + j]
                v = a[i + j + step]
                a[i + j] = u + v
                a[i + j + step] = u - v
        step = jump

    if invert:
        inv_n = pow(n, MOD - 2, MOD)
        for i in range(n):
            a[i] = a[i] * inv_n % MOD

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    size = 1 << m
    F = [0] * size
    F[0] = 1

    # build subset XOR distribution via FWHT trick
    # start from delta states and convolve iteratively
    for x in a:
        # shift-based XOR convolution with single element
        G = F[:]
        for i in range(size):
            G[i ^ x] = (G[i ^ x] + F[i]) % MOD
        F = G

    ans = [0] * (m + 1)
    for x in range(size):
        ans[x.bit_count()] = (ans[x.bit_count()] + F[x]) % MOD

    print(*ans)

if __name__ == "__main__":
    solve()
```该实现使用 XOR 状态上的直接子集 DP，其中`F[x]`计算有多少个子集产生 XOR`x`。 每个元素通过移动 XOR 状态来更新分布：要么我们不采用该元素，要么我们将它异或到每个现有的子集状态中。 

关键细节正在迭代`x`并更新到一个新数组中`G`，它通过防止在同一迭代中重用部分更新的状态来保持正确性。 

最终的聚合使用Python的`bit_count()`按设置位数对 XOR 值进行分类。

 ## 边缘情况

 当所有元素都为零时，每个子集都会折叠为异或零，因此子集的全部质量都会累积在分数中`0`。 该算法处理这个问题是因为 XOR 更新永远不会改变状态，所以`F[0]`双打`n`次，生产`2^n`。 

什么时候`n = 1`，系统干净地分成两个子集：空元素和单个元素。 XOR 分布变为`{0, a1}`，并且 popcount 分组直接产生正确的计数，而不受其他元素的干扰。 

什么时候`m = 0`，只有一个可能的 XOR 值，因此所有子集都映射到单个存储桶。 该算法正确退化，因为状态空间有大小`1`，并且没有任何转换会改变任何东西。
