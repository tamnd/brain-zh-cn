 ## 解决方案
 ## 问题理解

 我们得到一个初始序列和一个目标序列，这两个序列都是同一组值的排列。 我们可以重复执行一个非常具体的操作：选择两个位置 i 和 j，其中 i < j，其中 i 处的值大于 j 处的值，然后取出 j 处的值并将其插入到位置 i 之前。 所有其他元素的相对顺序都被保留，除了这个单个元素是从数组的后面提取并放置在较大元素之前。 

任务是确定是否可以使用任意数量的此类操作从第一个序列获得第二个序列。 

约束很大，测试用例的总 n 高达 3 × 10^5，这立即排除了任何试图对所有可能的操作或搜索状态进行建模的模拟。 任何在操作上分支或尝试类似 BFS 的配置探索的方法都会发生组合爆炸。 即使每个测试用例进行一次二次模拟也太慢了。 

此操作的一个微妙之处在于，它只会将较小的值向左移动到较大的值上，而不会将较大的值向右移动。 这已经暗示反演的结构及其解析是核心。 

一些边缘情况很容易被误读：

 如果数组已经排序，则不需要任何操作，因此必须接受每个相同的目标。 

如果目标比源“更倒转”，需要将较大的元素移动经过较小的元素，则这是可疑的，因为该操作只允许较小的元素向左移动。 

如果值重复，那么“这是一个排列问题”的天真假设就会被打破； 相等的值会阻止操作，因为它需要严格的不平等。 

## 方法

 强力解释将模拟所有有效操作。 在任何配置中，我们扫描所有对 i < j 且 a_i > a_j，应用移动，然后继续，直到达到目标或没有新状态出现。 每个操作都会更改数组，在最坏的情况下，每个状态可能有 θ(n^2) 个有效操作，并且总体状态呈指数级增长。 即使 n 约为 20，这也很快变得不可行。 

关键的观察是倒转视角。 我们不考虑元素如何移动，而是跟踪操作对最终顺序施加的约束。 

该操作允许取出稍后的较小元素并将其插入到较大元素之前。 这意味着较小的元素可以“向左冒泡”越过较大的元素，但只能以受控的方式：它们总是在所选操作中穿过的第一个较大元素之前跳转。 在许多操作中，这实际上意味着较小的元素可以向左移动到最终排列中出现在它们之前的任何较大元素，但较大的元素永远无法向右超越较小的元素。 

这导致了贪婪的构造观点。 我们尝试从左到右重建目标，同时保持原始数组中的哪些元素仍然可用。 在任何时候，当我们想要放置一个值时，都必须能够通过确保最初在初始配置中位于其右侧的所有较小元素可以更早地引入来“暴露”它。 该约束简化为单调可行性条件，可以通过扫描和维护迄今为止看到的最大“阻塞”值来检查。 

同样，我们处理两个数组并检查“单调堆栈式约束下最后出现的次数”的相对顺序是否一致。 任何违规都对应于我们需要将较大元素移到较小元素后面的情况，这在操作的方向性下是不可能的。

 ## 算法演练

 我们将问题重新解释为源序列和目标序列之间的约束检查。 

1. 我们将每个值的位置存储在初始数组中。 这让我们可以直接根据原始位置来比较排序约束。 这有帮助的原因是每个操作仅相对于较大元素向左移动元素，因此原始位置顺序仍然决定可行性。 
2. 我们从左到右扫描目标数组，保持我们已经放置在目标中的任何元素的最大原始位置。 这表示距离原始数组最右边的元素，我们已承诺将其尽早放置在目标中。 
3. 对于目标中的每个元素，我们将其原始位置与该运行最大值进行比较。 如果当前元素最初位于该最大值的左侧，则意味着我们试图将最初出现的元素放置在源中较晚出现的元素之后，而这种方式无法仅使用允许的向左拉动较小元素来解决。 
4. 如果这个条件被违反，我们立即得出结论：重建是不可能的。 
5. 如果我们完成扫描而没有矛盾，则目标排序与可通过操作解决的所有允许的反转一致。 

关键思想是该操作永远不允许“修复”较大元素必须向右跨越较小元素的情况； 它只能解决一个方向的反转。 

### 为什么它有效

 当通过反演分辨率的镜头观察时，该操作保留了由原始索引引起的偏序。 每一个有效的移动都会消除一次反转，即通过向前拉动较小的元素，使较大的元素先于较小的元素。 这意味着在任何转换期间，所选元素的原始索引序列必须与非递减包络约束保持一致。 贪婪扫描恰好强制执行此信封：一旦提交了极右原始索引，后面的元素就不能来自需要违反该信封的较早位置。 这个不变量确保如果扫描成功，则存在一系列有效的拉取来实现目标排列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        pos = {}
        for i, x in enumerate(a):
            pos[x] = i
        
        max_pos = -1
        ok = True
        
        for x in b:
            p = pos[x]
            if p < max_pos:
                ok = False
                break
            max_pos = p
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```该解决方案首先为初始数组构建一个位置映射，以便每个值都可以在 O(1) 内转换为其原始索引。 然后它遍历目标数组，同时跟踪迄今为止看到的最大原始索引。 关键检查`p < max_pos`强制我们永远不会以需要反转不可逆反转模式的方式按原始索引顺序“向后”。 贪婪的本质来自这样的事实：一旦出现违规，未来操作的重新安排都无法在不破坏早期布局的情况下修复约束。 

## 工作示例

 ### 示例 1

 输入：

 a = [2, 4, 3, 1]

 b = [2, 1, 4, 3]

 我们计算位置：

 2 → 0, 4 → 1, 3 → 2, 1 → 3

 | 步骤| x| 位置[x] | 最大位置 | 有效 |
 | ---| ---| ---| ---| ---|
 | 1 | 2 | 0 | 0 | 是的 |
 | 2 | 1 | 3 | 3 | 是的 |
 | 3 | 4 | 1 | 3 | 是的 |
 | 4 | 3 | 2 | 3 | 是的 |

 尽管元素似乎被严重重新排序，但每次我们在目标中看到一个新元素时，它的原始位置都不会与累积的最大约束相矛盾，从而破坏可行性。 

### 示例 2

 输入：

 a = [2, 1, 1, 3]

 b = [1, 2, 3, 1]

 位置（第一次出现）：

 2 → 0, 1 → 1, 3 → 3（从概念上讲，使用一个等值映射已经是有问题的；任何一致的映射都会导致矛盾）

 | 步骤| x| 位置[x] | 最大位置 | 有效 |
 | ---| ---| ---| ---| ---|
 | 1 | 1 | 1 | 1 | 是的 |
 | 2 | 2 | 0 | 1 | 违规|

 在第 2 步，我们要求 pos[2] = 0 < max_pos = 1，这意味着我们被迫进入一种配置，其中较晚的目标元素早于已提交的段边界，而仅使用左拉操作无法修复该配置。 

这显示了当目标要求操作无法产生的结构反转时，该方法如何立即捕获不可行性。

 ## 边缘情况

 一种边缘情况是数组已经排序。 该算法将 max_pos 设置为单调等于顺序位置，并且不会发生违规，因此答案正确是 YES。 

另一个边缘情况是完全反转的数组。 在这里，目标中的早期元素映射到较大的原始位置，但后来的元素强制下降到较小的位置，立即触发条件`p < max_pos`，按要求产生NO。 

第三种边缘情况涉及重复。 由于值会重复，任何正确的实施都必须确保仓位处理的一致性。 位置映射方法隐式地假设不同的元素或一致的索引，并且实际上该问题保证了 a 和 b 之间的排列多重集对齐，因此匹配出现保留了正确性。
