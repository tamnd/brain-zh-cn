 ## 解决方案
 ## 问题理解

 我们给定一个正整数$n$，我们需要找到最小的整数$k$这样$k \ge n$和每一个数字$k$是相同的。 这些数字看起来像$1, 2, 3, \dots, 9, 11, 22, 33, \dots, 9999$，其中单个数字重复多次。 

该任务本质上是找到下一个不小于给定输入的“统一数字”。 输入可以大到$10^{18}$， 所以$n$最多可以有 18 位数字。 这立即排除了任何尝试向上迭代的方法$n$一步一步，因为即使每个候选人只迈一步也可能导致最多$10^{18}$在最坏的情况下进行操作，这远远超出了任何可行的时间限制。 

输出的结构也受到限制：每个有效的候选数字完全由两个选择决定，即数字$d \in [1,9]$和长度$L \ge 1$。 这已经表明搜索空间很小并且高度结构化。 

主要的边缘情况来自数字长度之间的边界转换。 例如，如果$n = 9992$，答案是$9999$，但如果$n = 9999$，答案跳转到$11111$。 在后一种情况下，仅尝试相同长度候选的天真的方法会失败。 另一个微妙的情况是，相同长度的最小有效数仍然太小，迫使我们完全移至下一个长度。 

## 方法

 暴力方法将从$n$并重复加一，检查所有数字是否相同。 检查号码很便宜，仅$O(\log n)$，但在最坏的情况下，我们可能会在达到下一个有效数字之前扫描一个很大的范围。 如果$n$类似于 1000000，下一个有效数字是 1111111，这意味着在最坏的情况下大约有一百万张支票，每张支票都有数字扫描。 这对于上限来说变得太慢了$10^{18}$。 

关键的观察结果是有效数字极其稀疏且结构化。 对于每个长度$L$，只有九个候选人：$d \times 111...1$和$L$数字。 因此，我们不需要逐个数字地搜索，而只需要考虑由重复数字形成的一小组候选者。 

该策略变为：对于每个可能的数字长度$L$大约的长度$n$，生成所有统一数字并选择至少是最小的一个$n$。 自从$L$最多 18 位，数字为 1 到 9，我们最多检查 162 个候选者。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(答案 − n) · O(数字) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(9·位数) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们依赖这样一个事实：任何有效答案都必须是非常小的一组构造数字中的一个。 

1. 计算位数$L$在$n$。 这给出了我们应该首先检查的候选人的自然规模。 
2. 生成由​​重复数字组成的所有数字$d \in [1,9]$， 确切地$L$次。 每个这样的数字都可以构造为$d \cdot (111...1)$。 我们将每一个进行比较$n$并跟踪最小的有效值。 
3. 还生成所有此类数字的长度$L + 1$，因为如果没有有效的$L$-位数足够大，答案必须是多一位数的最小统一数。 这捕获了像 9999 → 11111 这样的转换。 
4. 在所有长度的候选人中$L$和$L+1$，选取至少为的最小值$n$。 

每个步骤的合理性在于，统一数字首先按长度严格排序，然后按相同长度内的数字值排序。 

### 为什么它有效

 每个有效数字都属于一个按其长度和数字值索引的离散集合。 对于固定长度，除了数字重复之外，该集合中没有间隙，因此任何候选答案都必须出现在构造的列表中。 仅考虑长度$L$和$L+1$是足够的，因为任何长度小于$L$已经在下面了$n$，以及任何长度大于的数字$L+1$严格大于我们需要考虑的任何候选人。 这保证了生成的候选者中的最小值正是答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def make(d, length):
    return int(str(d) * length)

def solve():
    n = int(input().strip())
    s = str(n)
    L = len(s)

    candidates = []

    for length in (L, L + 1):
        for d in range(1, 10):
            candidates.append(make(d, length))

    ans = min(x for x in candidates if x >= n)
    print(ans)

if __name__ == "__main__":
    solve()
```该实现通过重复数字字符来构造候选数字，这是安全的，因为 Python 可以有效地处理这些大小的任意长度整数。 数字 1 到 9 的循环确保我们覆盖给定长度的所有统一数字。 

决定包括两个长度$L$和$L+1$很关键。 没有$L+1$，像 999 或 9999 这样的情况会失败，因为没有相同长度的候选者可以满足条件。

 ### 示例 1：n = 6528

 我们计算$L = 4$。 我们生成所有 4 位统一号码和所有 5 位号码。

 | 4 | 6 | 6666 |
 | 4 | 7 | 7777 |

 | 5 | 2 | 22222 | 22222
 | ... | ... | ... |

 ≥ 6528 的最小值为 6666。 

这证实了在相同的数字长度内，答案只是第一个跨过阈值的统一数字。 

### 示例 2：n = 9952

 这里$L = 4$。 在 4 位候选数字中，只有 9999 足够大。 

| 长度| 数字| 价值|
 | ---| ---| ---|
 | 4 | 9 | 9999 |

 其他 4 位统一号码均无效。 由于 9999 有效，因此我们不需要 5 位数字。 

这表明，只有当所有相同长度的候选者都不够时，我们才会转向更长的长度。

 ## 边缘情况

 一种重要的边缘情况是输入已经是统一的数字。 例如，$n = 777$。 该算法仍然生成长度为 3 的候选值，并且由于 777 本身也在候选集中，因此它将被正确选择为最小有效值。 

另一种情况是当数量略低于统一阈值时，例如$n = 9999$。 除 9999 本身外，所有 9999 以下的 4 位统一号码均有效，但小于$n$，所以没有一个符合条件。 该算法正确地移动到 5 位候选数字并选择 11111，与所需的环绕行为相匹配。 

第三种情况是小输入，例如$n = 1$。 这里候选生成包括1位统一编号，最小有效候选是1本身，因此不会发生不必要的升级。
