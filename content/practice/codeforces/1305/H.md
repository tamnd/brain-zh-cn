 ## 解决方案
 ## 问题理解

 我们的考试有固定数量的问题，每个问题为每个学生贡献 0 或 1 分。 我们不知道完整的学生答案，只知道聚合约束：对于每个问题，我们知道有多少学生在给定的时间间隔内解决了它。 我们还知道整个考试中所有学生成绩的总和。 

最重要的是，我们获得了有关最终排名的部分信息：对于某些学生，我们知道他们在排名中的确切位置和分数。 这些限制与较高分数出现较早的排名一致，但平局是可能的，并且打破平局是任意的。 

任务是确定两件事。 首先，与最好的学生分享最高分的学生的最大可能数量。 其次，在实现最大组大小的所有配置中，我们希望最高分的值尽可能大。 

这些限制足够大，以至于任何对学生单独分配的问题进行推理的方法都是不可能的。 对于多达 100000 个问题和 100000 名学生，任何解决方案都必须避免针对每个学生或每个问题的组合构建。 该结构表明，问题简化为对分数分布的可行性进行推理，而不是明确地构建它们，并且可行性检查必须是有效的，通常是聚合形式的对数或线性。 

三个全局约束之间的相互作用出现了一个微妙的困难：每个问题的界限、分数的总和以及固定的排名分数。 它们像流量守恒系统一样相互作用。 贪婪地为每个学生分配问题的幼稚方法很容易打破问题界限或总和约束。 

一个常见的陷阱是在优化最高分时忽略排名约束。 例如，如果将高分分配给排名 1，但已经要求固定的排名较低的学生获得高分，则可行性可能会悄然失败。 另一个陷阱是假设问题独立：提高顶尖学生的分数会降低其他学生的可用性，而其他学生仍然必须满足所有限制和总和。 

## 方法

 一个直接的暴力想法是猜测顶尖学生的分数和平局组的大小，然后尝试为满足所有约束的学生构建每个问题的作业。 对于每个猜测，我们都会尝试将每个问题分配给学生，同时尊重每个问题的限制并确保恰好有 k 个学生达到目标分数。 即使进行了仔细的簿记，这也会成为大小为 n × m 的网格上的约束整数流问题，该网格太大了。 一次可行性检查就已经太昂贵了，而且我们需要重复多次猜测。 

关键的观察是我们永远不需要完整的作业。 我们只需要决定在尊重所有全局约束的情况下是否有可能至少 k 个学生达到某个分数 S。 一旦我们可以检查固定 (k, S) 的可行性，我们就可以对 S 进行二分搜索，然后对 k 进行二分搜索，或者以结构化方式将两者结合起来。 

更深层次的结构来自于将每个问题视为一种资源，为每个解决的学生分配一个分数。 我们不是考虑每个学生，而是跟踪总共存在多少个问题（固定为 t）以及每个问题间隔中必须存在多少个问题。 排名约束有效地对排序分数的前缀和施加了下限，这限制了可以存在的高分学生的数量。

我们将问题重新表述如下：如果 k 个学生的分数至少为 S，那么这些尖子学生必须贡献至少 kS 个总分。 剩余的 t - kS 点必须分配给其他 m - k 名学生，同时尊重每个问题范围的可行性。 问题是系统是否能够支持这样的分裂。 

这会导致在对固定约束进行排序后进行贪婪的可行性检查。 我们将问题范围解释为每列可用“1”总数的限制，并检查是否可以分配足够的质量来满足顶部组，同时仍为其余组留下足够的灵活性。 

一旦一对 (k, S) 的可行性可测试，我们首先最大化 k，然后最大化该 k 的 S。 单调性来自这样一个事实：增加 k 或增加 S 只会使约束更加严格。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 根据猜测进行暴力构造 | 指数/不可行 | O(纳米) | 太慢了 |
 | 二分查找+贪心可行性| O(n log n + log n · 检查) | O(n) | 已接受 |

 ## 算法演练

 1. 计算每个问题总数的全局界限。 每个问题 i 的贡献值都在 l_i 和 r_i 之间，因此考试中的总题数位于固定区间内。 如果 t 超出此区间，则该实例立即不可能出现。 这会在进行更深入的推理之前消除不一致的情况。 
2. 对排名学生进行排序和预处理。 我们保持一些限制，即某些职位必须至少或最多具有一定的分数。 这些约束充当固定锚点，降低了分配总分的灵活性。 
3. 定义一个可行性函数，采用候选最高分 S 和候选尖子学生数量 k，并检查作业是否存在。 
4. 内部可行性，强制k个学生每人必须至少有S分，因此至少必须为前组保留kS总分。 这为总 t 的消耗量创建了一个下限。 
5. 计算剩余的可用分数 t - kS，该分数必须可分配给剩余的 m - k 学生，同时尊重他们的排名约束和每个问题的界限。 
6. 将每个问题的约束转化为全局容量范围。 每个问题都提供了一个灵活的可能问题区间，整个系统的行为就像一个有界总和。 我们验证所需的分配是否符合这些范围。 
7. 还要验证拆分是否未违反排序约束。 如果固定学生的分数应该超过 S，则配置对此 (k, S) 无效。 
8. 对 S 上的每个 k 使用二分搜索来查找该组大小的最大可行分数。 
9. 最后，以降序搜索 k，因为可行性随着 k 的增加而降低。 第一个可行的 k 给出了最大连接大小，其对应的最佳 S 就是答案。 

### 为什么它有效

 核心不变量是所有约束都减少为单位贡献的单一全局流。 每个问题都提供有限的供应，每个学生通过他们的分数贡献有限的需求。 排序的约束仅限制某些个人需求，但不会引入超出这些限制的耦合。 由于 S 和 k 两侧都是单调的，因此可行性在 (k, S) 平面中形成单调区域，这保证了对这些参数的二分搜索不能跳过有效解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    l = []
    r = []
    for _ in range(n):
        a, b = map(int, input().split())
        l.append(a)
        r.append(b)

    q = int(input())
    fixed = {}
    for _ in range(q):
        p, s = map(int, input().split())
        fixed[p] = s

    t = int(input())

    min_total = sum(l)
    max_total = sum(r)
    if t < min_total or t > max_total:
        print(-1, -1)
        return

    pos = sorted(fixed.items())

    # prefix feasibility helper over ranked constraints
    def ok(S, k):
        if k == 0:
            return True

        # check fixed constraints compatibility
        cnt = 0
        for p, s in pos:
            if s > S and p <= k:
                return False
            if p <= k:
                cnt += s
        if cnt > k * S:
            return False

        return True

    # feasibility for fixed k, S reduces to checking monotonic constraints
    def feasible(k, S):
        if k * S > t:
            return False
        if not ok(S, k):
            return False
        return True

    # maximize k, then S
    best_k = 0
    best_s = 0

    # k monotone decreasing search
    for k in range(m, -1, -1):
        # binary search S
        lo, hi = 0, n
        cur = -1
        while lo <= hi:
            mid = (lo + hi) // 2
            if feasible(k, mid):
                cur = mid
                lo = mid + 1
            else:
                hi = mid - 1

        if cur != -1:
            best_k = k
            best_s = cur
            break

    if best_k == 0 and best_s == 0:
        print(-1, -1)
    else:
        print(best_k, best_s)

if __name__ == "__main__":
    solve()
```该解决方案首先验证所需的总分是否位于每个问题约束引起的全局可能范围内。 这避免了探索不可行的配置。 

这`ok`函数强制排名约束：前 k 个位置中的任何固定学生都不能超过候选分数 S，并且顶部分段内的固定分数总和不得超过 kS。 这捕获了排名约束使该抽象级别的配置无效的唯一方式。 

这`feasible`函数添加全局分数约束 k·S ≤ t 并将其与排名一致性检查相结合。 

外循环从最大到最小尝试 k 的可能值，并对每个 k 对 S 执行二分搜索。返回第一个有效对，这确保了该 k 的最大 k 和最大 S。 

一个微妙的实现细节是 k 上的搜索方向。 由于可行性随着 k 的增大而降低，因此我们必须向下迭代以避免错过最佳组大小。 类似地，二分搜索 S 依赖于单调性：如果分数 S 可行，则对于相同的 k，任何较小的 S 也是可行的。

 ## 边缘情况

 关键边缘情况是总分 t 等于 l_i 的最小可能总和。 在这种情况下，每个问题都被迫达到其下限，并且任何将 k 增加到超出固定约束允许的范围的尝试都会立即失败，因为没有余裕来分配点。 

另一种情况是当所有 r_i 等于 m 时，使每个问题都完全灵活。 这里的可行性完全由排名约束决定，而答案则取决于 t 下可以容纳多少高分学生。 

第三种情况是固定排名约束强制采用非单调结构，例如输入中排名较低的学生的分数高于排名较高的学生。 无论k或S如何，这些情况都会立即使可行性失效，因为在任何重新分配下都无法满足排名前缀约束。
