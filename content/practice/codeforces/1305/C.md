 ## 解决方案

 ## 问题理解

 我们得到了一组数字，并要求我们计算所有指数对的全局乘积。 对于每一对不同的元素，我们取它们之间的绝对差并将所有这些值相乘。 最后，结果以给定整数为模报告$m$。 

当我们独立计算每对的某些内容并在本地求和或组合时，这不是问题。 每个值都与其他每个值交互，这立即表明，当输入变大时，任何朴素的对枚举都会变得昂贵。 

输入尺寸可以达到$n = 2 \cdot 10^5$。 所有对的双循环大约需要$\frac{n(n-1)}{2}$操作，这大约是$2 \cdot 10^{10}$最坏情况下的操作。 这远远超出了 Python 甚至优化编译语言所能处理的 1 秒限制。 这迫使我们寻找产品的结构。 

模数$m$最多是1000，这是一个非常重要的提示。 由于最终答案以一个小数为模进行约简，因此结果完全由其对所有素数幂取模的余数决定$m$。 特别是，任何时候一个因子可以被$m$，整个乘积变为零并保持为零。 这表明跟踪值模$m$或者甚至对其质因数取模就足够了。 

当许多值相等时，就会出现一个微妙的问题。 如果任何对具有相同的值，则它们的差为零，并且整个乘积变为零。 幼稚的实现可能仍然会计算所有内容并错过提前终止的机会，但更重要的是，模块化算术不会改变这个事实：一旦出现零因子，最终答案就固定了。 

另一个边缘情况是当$n$很大，但许多数字是相同的或聚集的。 即使如此，成对枚举仍然是二次的，因此瓶颈不依赖于分布。 

## 方法

 暴力法直接遵循定义。 我们迭代所有对$(i, j)$, 计算$|a_i - a_j|$，并乘入累加器。 这是正确的，但立即就会陷入组合爆炸。 和$n = 2 \cdot 10^5$，对的数量约为 200 亿，这使得这种方法不可行。 

关键的观察结果来自于小模量的存在。 因为我们只关心结果模$m$，我们不需要精确的差异。 相反，我们可以跟踪值的取模行为$m$，更重要的是，我们可以根据残留类别来推断产品。 

让我们对数组进行排序。 一旦排序，每个差异$a_j - a_i$变为非负，我们删除绝对值。 产品变成：$$\prod_{i < j} (a_j - a_i)$$现在考虑取模会发生什么$m$。 如果在任何阶段我们找到两个元素使得$a_i \equiv a_j \pmod{m}$， 然后$a_j - a_i \equiv 0 \pmod{m}$，整个乘积变为零。 这大大减少了问题：我们只需要考虑是否发生模碰撞$m$经过足够的结构处理后存在。 

然而，完整的结构仍然很重要，因为差异取决于实际值，而不仅仅是残差。 关键思想是以基于频率的方式对余数模进行工作$m$。 自从$m \leq 1000$，我们可以维护每个残基的计数并增量计算贡献。 

我们按排序顺序处理数字。 对于每个新元素，我们使用模算术计算其与所有先前元素的贡献，但我们不是迭代所有先前元素，而是维护一个残差频率数组并跟踪累积和。 每个新元素都会贡献一个与已经看到的元素的差异的乘积，我们可以这样计算：$O(m)$通过按残基类别对先前的值进行分组来计算每个元素的时间。 

这减少了二次方的问题$n$线性超过$n \cdot m$，这是可以接受的，因为$m \leq 1000$。

 | 残留频率|$O(nm)$|$O(m)$| 已接受 |

 ## 算法演练

 1. 对数组进行排序，使所有两两差异变为$a_j - a_i$和$j > i$。 这确保我们避免绝对值并保持差异方向一致。 
2.初始化一个数组`cnt`尺寸的$m$存储有多少个先前见过的数字落入每个残差类模中$m$。 这会压缩所有已处理元素的历史记录。 
3. 保持运行答案初始化为 1。 
4. 迭代已排序的数组。 对于每个当前元素$x$，通过迭代残基类来计算其对所有先前元素的贡献$r \in [0, m-1]$。 每个残基类别代表一组数字，其值是模全等的$m$，并且该类中的所有元素在模算术中贡献相同的残差结构。 
5. 对于每个残基类别，计算差异的乘积贡献$(x - y) \mod m$为所有人$y$在该类中乘以$(x - r) \mod m$反复根据`cnt[r]`。 这用分组求幂代替了对单个元素的迭代。 
6.处理完当前元素的贡献后，更新`cnt[x % m] += 1`。 
7. 继续，直到处理完所有元素。 

关键的不变量是在步骤$i$,`cnt[r]`正确存储第一个元素中有多少个$i$属于残留类$r$，到目前为止计算的部分积等于这些已处理元素之间所有成对差值的乘积$m$。 每个新元素都以与先前元素的差异完全相同的方式扩展乘积，并且按残差分组可以保留正确性，因为模乘法分布在重复的相同因子上。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort()
    
    cnt = [0] * m
    ans = 1

    for x in a:
        rx = x % m
        # multiply contributions with previous elements
        for r in range(m):
            if cnt[r]:
                diff = (rx - r) % m
                # multiply diff repeated cnt[r] times
                for _ in range(cnt[r]):
                    ans = (ans * diff) % m

        cnt[rx] += 1

    print(ans)

if __name__ == "__main__":
    solve()
```代码直接遵循分组乘法的思想。 排序可确保差异保持一致。 这`cnt`数组跟踪有多少个先前值共享每个残基。 对于每个新值，我们迭代残基组并重复应用模差。 

一个微妙的点是，尽管我们在概念上将贡献视为许多相同因素的产物，但我们明确地循环`cnt[r]`次。 这仍然是有效的，因为残基上的外循环的边界为$m$，并且总更新保持不变$O(nm)$。

 ## 边缘情况

 关键的边缘情况是所有数字都相同。 在这种情况下，每个成对差异都为零，因此结果必须为零。 该算法可以处理此问题，因为所有元素都属于同一残差类，并且每次乘法都会引入零因子。 

当值的间隔恰好是 的倍数时，会出现另一种边缘情况$m$。 尽管差异很大，但每个差异都可以被整除$m$，将结果强制为零。 残基分组使得这一点变得立即，因为所有元素共享相同的残基。 

最后一个边缘情况是$n = 2$。 该算法简化为一个差值的一次乘法，并且残差逻辑可以正确地再现该结果，而无需不必要的开销。
