 ## 解决方案
 ## 问题理解

 我们有一群人，每个人都有一个关联的整数值，可以解释为位掩码。 这些人可以通过加入一个行动产生利润的系统来形成一个网络：一旦有人加入，他们就可以“邀请”尚未加入的人，每次邀请都会产生等于邀请者价值的利润。 

关键的限制是邀请只能按照特殊的兼容性规则进行。 如果两个人的值的按位与为零，则认为他们是直接兼容的，这意味着他们的二进制表示不共享公共设置位。 这种兼容性定义了哪些对可以直接交互，但实际过程允许通过已经加入的成员进行间接合作，因此群体形成的结构比个体边缘更重要。 

任务是确定加入和邀请人员的顺序，以使所有参与者的总利润最大化。 

约束最多允许 200,000 人，值最大为 2×10^5。 试图模拟所有子集或所有邀请顺序的简单方法立即是不可行的，因为即使是二次行为也太慢了。 任何解决方案都必须依赖于掩码子集的位级结构和聚合。 

当许多值共享位时，例如当所有数字都是 2 的幂时，就会出现微妙的极端情况。 在这种情况下，没有两个不同的数字是兼容的，因此交互受到严格限制，并且最优策略崩溃为选择局部最佳转换而不是全局混合。 另一个极端情况是零出现时，因为零与每个数字兼容，完全改变了连接结构，并且通常充当通用连接器。 

## 方法

 强力解释将尝试将过程模拟为所有人的图形问题，如果两个节点的按位与为零，则连接两个节点，然后搜索激活和邀请的最佳顺序。 这很快就会变得棘手，因为在像许多小位数这样的密集情况下，该图最多可以有 200,000 个节点和 O(n^2) 条边。 即使显式构建图也已经失败。 

即使我们避免完整的图构造，我们也可以尝试对位掩码的子集或所有子集进行动态编程。 这也会失败，因为状态空间将依赖于 2^18 种可能的掩码，但个体之间的简单转换仍然需要迭代每个状态的所有人。 

关键的观察结果是，该过程实际上并不是关于个人，而是关于按位掩码进行分组。 如果多人拥有相同的价值观，他们的贡献是可以互换的。 更重要的是，兼容性规则仅取决于按位不相交，这建议在掩码上使用 DP，其中我们聚合相同掩码的贡献。 

我们将问题重新解释为选择掩码的排序，其中掩码只有在通过兼容的先前激活的掩码“激活”后才能贡献其价值。 这导致了位掩码上的经典子集 DP，其中我们计算每个掩码的最佳可实现贡献并通过补关系进行传播。 

关键的转变是根据所有人的价值来压缩所有人，对每个掩码的贡献进行求和，然后在子集上运行 DP，在子集中我们保持尊重兼容性约束的掩码的最佳可实现总和。 我们不是迭代成对的人，而是迭代掩模并使用 SOS 风格的转换来有效地组合状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) 或更糟 | O(n) | 太慢了|
 | 最佳 | O(2^k·k) 其中 k ≤ 18 | O(2^k) | O(2^k) | 已接受 |

 ## 算法演练

1. 我们首先通过计算有多少人拥有每个值来压缩输入。 我们没有单独对待个体，而是将每个面具视为贡献的总重量，等于佩戴该面具的人的年龄总和。 这是必要的，因为所有相同的掩码在兼容性和贡献方面表现对称。 
2. 我们计算所有掩模上的频率数组，直到最大值。 每个条目都存储该掩码贡献的总利润权重。 
3. 我们在所有掩码上初始化一个 DP 数组，其中 dp[mask] 表示按位或包含在掩码内的人员子集的最佳可实现贡献。 该公式与标准掩模子集和技术一致。 
4. 我们根据实现风格执行 SOS DP（超集求和）或子集 DP。 对于每一位，我们传播值，以便 dp[mask] 累积来自所有子掩码的贡献。 原因是与给定掩码兼容的任何配置都必须由不会引入冲突位的子掩码组成。 
5. 传播后，我们通过考虑所有掩码并在有效的不相交合并条件下获取最大可实现的贡献来计算最终答案。 最佳结构对应于组合独立的比特分量而不重叠，并且DP确保考虑所有有效组合。 
6. 最终结果是所有dp状态中的最佳值，代表最优邀请排序所能实现的最大总利润。 

### 为什么它有效

 核心不变量是，处理每个位维度后，dp 正确地表示与处理位一致的所有子集上可实现的最佳聚合。 由于兼容性仅取决于按位不相交，因此任何有效的人员分组都准确对应于将位划分为独立子集。 SOS DP 确保每个有效子集组合仅被考虑一次，并且不会将无效组合（具有重叠位）合并到状态中，从而保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    MAXB = 18
    N = 1 << MAXB
    
    freq = [0] * N
    for x in a:
        freq[x] += x
    
    dp = freq[:]
    
    for b in range(MAXB):
        for mask in range(N):
            if mask & (1 << b):
                dp[mask] = max(dp[mask], dp[mask ^ (1 << b)])
    
    ans = max(dp)
    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先聚合每个掩码的所有贡献，以便立即组合重复的值。 这避免了稍后在 DP 中重复处理相同的状态。 

DP 数组直接使用这些聚合值进行初始化，这意味着每个掩码都以其自己的基线贡献开始。 

转换循环是经典的 SOS DP 步骤：对于每个位，我们允许状态从其子掩码继承最佳值，而无需设置该位。 这确保了每个面罩都积累了较小、兼容组件的最佳组合。 

最后，取所有状态的最大值，因为任何有效的构造都对应于 DP 空间中表示的某些子集配置。 

这里的一个常见陷阱是混淆子集 DP 方向。 错误地使用子掩码转换或以错误的顺序迭代会破坏正确性。 就地更新是有效的，因为我们总是根据设置位从较小的掩码传播到较大的掩码。

 ## 边缘情况

 当所有值都相同时，每个人都有相同的掩码，因此频率压缩将输入压缩为单一状态。 DP 只看到一个活动掩模并返回其聚合贡献，这反映出不可能进行跨掩模交互。 

当零出现时，它引入了一个没有位的掩码，它与所有其他掩码兼容。 用 DP 术语来说，它充当源状态，可以不受限制地在所有掩模上传播改进，这就是为什么它经常间接增加可实现的总数。 

当所有数字都是 2 的幂时，每个掩码都恰好设置了一位。 DP 退化为每比特独立的分量，并且只有不相交的单比特掩码的组合才起作用，这通过比特上的子集传播正确地捕获。
