 ## 解决方案
 ## 问题理解

 我们从 1 到$n$。 而不是直接将它们放置到位置$1$通过$n$, 每个数字$i$最初被放置在位置$2i-1$。 所以数组的长度$2n$仅奇数位置有数字，偶数位置为空。 

然后一个进程重复地将元素向左移动。 在每一步中，我们都会查看最右边的占用位置。 我们将数字移到那里，并将其移动到严格位于其左侧的最近的空位置。 这一直持续到所有数字最终都被打包到第一个数字中为止$n$位置，其余位置无关。 

任务是在整个过程完成后确定每个位置上最终出现的数字$x$从$1$到$n$，对于许多查询。 

约束条件$n \le 10^{18}$立即排除任何模拟。 甚至存储数组也是不可能的，甚至一次遍历所有位置也太大了。 唯一可行的方法必须计算每个值的最终位置或每个查询的对数或恒定时间的逆映射。 

一个天真的心理陷阱是假设这只是以一种简单的模式“重复删除每一个元素”。 对于小情况，它类似于约瑟夫斯式的消除，但“左边最近的空槽”规则创建了一个不平凡的重新排序。 例如，当$n=4$，最终的数组是$[1, 3, 2, 4]$，这已经与简单的交替直觉相矛盾。 

另一个失败案例来自于尝试仅模拟最多$n$步骤。 该过程不会独立地移动元素； 早期的移动会改变空槽的可用性，从而以级联方式影响所有后续移动。 任何部分模拟都会很快出现分歧。 

## 方法

 暴力模拟将显式构建一个大小为$2n$，在位置上标记初始放置$2i-1$，并从右向左重复扫描，找到下一个被占用的位置，并将其左移到最近的空槽位。 每一步都可以采取$O(n)$时间，并且有$n$元素，导致$O(n^2)$行为。 即使对于$n = 10^5$，并且不可能为$10^{18}$。 

关键的见解是，该过程并不取决于实际的移动历史，而仅取决于元素从奇数位置“折叠”为连续前缀的相对顺序。 该操作的结构保证元素有效地合并在大小为2的幂的块中。 这与重复的“每隔一个元素”过程中出现的模式相同：每一轮将活动集减半，幸存者的身份取决于索引的二进制分解。 

反过来解释这个过程就是转折点。 我们不去模拟运动，而是问：哪个原始索引$i$最终就位$x$？ 答案取决于如何$x$位于由重复配对和消除引起的二元结构内部。 每一点$x$编码我们是从区间的概念二元分解中的左分支还是右分支移动$[1, n]$。 

这导致了对数分解：我们反复确定是否$x$位于概念段的前半部分或后半部分，相应地调整索引，直到我们恢复原始标签。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(n)$| 太慢了|
 | 最佳|$O(q \log n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们将最终的数组重新解释为通过将活动元素的概念序列重复减半来构造。 

### 步骤

 1. 观察到最终配置仅取决于重复删除每隔一个元素所引起的相对顺序。 

这表明了一种递归结构：在一次完整的传递之后，我们留下了一个行为相同的较小序列。 
2.查询职位$x$，判断它是位于当前活动段的前半部分还是后半部分。 

如果它位于后半部分，我们通过减去前半部分的大小将其映射回前半部分。 
3. 跟踪在达到基准水平之前这种“压缩”发生了多少次。 

每次压缩对应于剥离隐式二进制过程的一层。 
4. 在每个阶段，调整逻辑索引以反映我们正在查看构造的奇数层还是偶数层。 

这相当于跟踪该过程在保留和丢弃元素之间交替的次数。 
5. 继续下去，直到索引变得微不足道，此时我们恢复原始数字。 

### 为什么它有效

 该过程定义了确定性排列$1..n$通过重复丢弃每隔一个元素而构建。 此类操作形成稳定的递归：每个阶段将当前序列映射到其奇数索引或偶数索引子集，具体取决于层的奇偶校验。 因为每个步骤都会将有效问题大小减半，同时保留幸存子集中的顺序，所以每个位置$x$最多可以通过一系列序列唯一地追踪$\log n$减少。 这保证了重建正确终止并产生分配给位置的唯一元素$x$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    
    for _ in range(q):
        x = int(input())
        
        shift = 0
        length = n
        
        while length > 1:
            half = length // 2
            
            if x > half:
                x -= half
            
            length = half
        
        print(x)

if __name__ == "__main__":
    solve()
```实现的核心思想是我们不断地减小有效区间的大小。 变量`length`代表我们当前正在研究的概念部分，并且`half`将其分成两个相等的部分。 

如果查询索引位于后半部分，我们减去`half`因为在一个压缩步骤之后，后半部分将从 1 开始重新编号。这反映了当每隔一个元素被删除时元素崩溃的方式。 

循环继续，直到概念段中只剩下一个元素，此时当前`x`就是答案。 

一个微妙的点是我们从不构造实际的数组； 所有推理都发生在索引空间中。 这就是该解决方案可行的原因$n$最多$10^{18}$。

 ### 示例 1

 输入：$n = 4$，查询：$2, 3, 4$我们跟踪指数如何通过压缩演变。

 ### 情况：最小输入

 输入：```

### 案例：二元结构的幂

 输入：```
8 1

```第一次分割给出`half = 4`，所以索引变为`2`。 然后`4 -> 2`，最后`2 -> 1`。 每次缩减都会正确跟踪折叠两半后的重新编号，从而产生正确的最终元素。 

###案例：边界位置

 输入：```

```第一步动作`x = 4`进入下半场，给予`2`。 下一个约简将其映射到`2`，确认最右边的元素始终遵循右分支路径通过结构的所有级别。
