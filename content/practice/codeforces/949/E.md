 ## 解决方案
 ## 问题理解

 我们可以构建多组“硬币”，其中每个硬币的值可以是 2 的正幂或负幂。 在每一轮中，都会宣布一个目标整数，并且我们必须能够选择固定硬币的某个子集，以便它们的总和等于该目标。 回合结束后，硬币会被返还，因此相同的多重集必须对每个查询值独立工作。 

任务是选择这样一个具有最小大小的多重集，以便每个给定的目标值都可以表示为子集和。 

这些约束在轮数上推动线性或接近线性的解决方案。 由于值最多为 100,000 个，幅度最多为 100,000 个，因此任何尝试针对每个查询独立重新计算表示的解决方案都将重复对每个值执行对数或更差的工作，并且如果它还尝试对子集进行组合搜索，则可能会变得太慢。 

一个天真的解释会尝试为每个查询分配一个新的二进制分解，然后合并所有所需的硬币。 但这会失败，因为不同的数字可能需要在相同的 2 次幂上选择相互冲突的有符号数字。 真正的困难在于单个固定多重集必须同时支持所有表示。 

当值跨查询“取消”时，会出现微妙的边缘情况。 例如，如果一个查询是 1，另一个查询是 -1，一种简单的方法可能会得出需要一枚 +1 硬币和一枚 -1 硬币的结论。 然而，通过选择硬币或空子集，单个 +1 硬币就足以满足 1 和 -1 的要求，因为可以通过跨二进制位置借用来形成负表示。 这种跨位的交互正是导致本地每个数字决策不正确的原因。 

当多个值强制重复进位时，例如交替大的正值和负值，会出现另一种边缘情况。 忽略进位传播的贪婪的每比特计数将低估对高阶硬币的需求。 

## 方法

 暴力策略将尝试找到最小的多重集，然后通过检查每个目标的每个子集和的可能性来验证它。 即使我们将自己限制为二的幂，这也会退化为一个巨大的状态空间。 每个硬币每轮都可以使用或不使用，验证 100,000 个目标的可表示性将需要重复的子集和计算，每次都会花费指数或伪多项式时间。 即使总和超过 100,000 的动态规划也会对每个候选配置重复进行，这是不可行的。 

关键的观察结果是，二的幂的行为就像二进制位置系统中的数字。 子集和条件变成了我们是否可以在所有位位置上使用固定符号数字表示来表示每个目标的问题。 我们不是考虑每个数字，而是将所有数字聚合到每个位位置的共享“需求”中，并模拟带有进位的二进制加法的全局行为。 

我们同时处理所有目标值，累积每个位需要多少次，并将多余或不足作为进位向上传播。 每个位位置的绝对不平衡告诉我们必须包含多少个具有该功率的代币。 这将问题转化为维护所有约束的全局平衡二进制表示。

 ## 算法演练

 我们用二进制解释每个数字并保持每个位位置的运行不平衡，模拟有符号的二进制表示需要如何调整以满足所有约束。

1. 将每个输入数字转换为其跨位位置的二进制贡献，将每个设置位视为该位置的 +1 需求，将每个负数视为 -1 需求。 
2. 维护数组`cur[k]`表示位位置处累积的有符号需求`k`。 
3. 对于每个输入数字，将其贡献添加到`cur`。 
4. 更新一个位位置后，立即通过模拟二进制进位行为来解决：

 如果`cur[k]`超过 1 或小于 -1，我们将超出的部分推到下一个位位置`k+1`除以 2，只保留余数`cur[k]`。 
5、处理完所有数字后，求绝对值`cur[k]`表示我们必须包含多少枚价值 ±2^k 的硬币。 
6. 输出所有这些硬币，根据 的符号使用正号或负号`cur[k]`。 

关键点是，每次进位操作都相当于用一枚价值为 2^(k+1) 的硬币替换两枚价值为 2^k 的硬币，从而在最小化计数的同时保留了可表示性。 

### 为什么它有效

 在每一位位置，我们都保持不变`cur[k]`表示处理到目前为止看到的所有输入后，有符号二进制展开式中所需的净系数。 每当这个系数超过单个有符号数字的可表示范围时，我们就会使用二进制进位规则对其进行标准化，该规则对应于将冗余硬币合并为更高价值的硬币。 

因为子集对 2 的幂求和形成了位置数系统，所以这种归一化不会改变可表示的整数集。 最后，每个位位置存储不可避免的单位贡献的最小数量，这直接转化为所需的最小硬币数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    MAXB = 20
    cur = [0] * (MAXB + 5)

    for x in a:
        sign = 1
        if x < 0:
            sign = -1
            x = -x

        b = 0
        while x > 0:
            if x & 1:
                cur[b] += sign
            x >>= 1
            b += 1

        k = 0
        while k < len(cur):
            if cur[k] > 1:
                carry = cur[k] // 2
                cur[k] -= carry * 2
                cur[k + 1] += carry
            elif cur[k] < -1:
                carry = (-cur[k]) // 2
                cur[k] += carry * 2
                cur[k + 1] -= carry
            k += 1

    res = []
    for i, v in enumerate(cur):
        for _ in range(abs(v)):
            res.append((1 if v > 0 else -1) * (1 << i))

    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```该代码维护了一个全局的有符号数字不平衡数组。 每个数字被分解为位并添加符号。 插入后，规范化步骤立即强制每个位置保持在 {-1, 0, 1} 范围内，直至进位。 

进位传播循环是关键的微妙之处。 它必须继续前进，因为将多余的内容推入更高位本身会再次产生溢出。 这就是循环向上扫描而不是仅处理当前位置的原因。 

最终的重建只是将每个非零数字扩展为多个±2 的幂硬币。 

## 工作示例

 考虑单个值为 9 的输入。 

我们将 9 处理为二进制 1001，在位 0 和位 3 处产生贡献。不存在其他约束，因此除了标准化之外不需要进行进位调整。 

| 步骤| 位 0 | 位 1 | 位 2 | 位 3 | 行动|
 | --- | --- | --- | --- | --- | --- |
 | 添加 9 | 1 | 0 | 0 | 1 | 初始分解|
 | 标准化 | 1 | 0 | 0 | 1 | 无需携带|

 最终的硬币是1和8，它们直接组合为9。 

现在考虑混合输入：1、-1、2。 

处理 1 在位 0 处加 +1。处理 -1 在位 0 处减 1，将其取消。 Processing 2 adds +1 at bit 1.

 | 步骤| 位 0 | 位 1 | 行动|
 | --- | --- | --- | --- |
 | +1 | 1 | 0 | 添加贡献 |
 | -1 | 0 | 0 | 取消 |
 | +2 | 0 | 1 | 添加贡献 |

 最终的多重集仅包含一枚价值为 2 的硬币，这足以满足所有查询。 

这些痕迹表明，不同输入之间的取消自然是通过符号累加而不是按数字构造来处理的。

 ## 边缘情况

 一个关键的边缘情况是输入之间的完全取消，例如`1 -1 1 -1`。 该算法反复取消贡献`cur[0]`，保留所有高位不变。 该不变量确保不会引入不必要的高位硬币，并且最终输出为空。 

另一个边缘情况是重复溢出，例如许多值，例如`1`重复100,000次。 位 0 位置累积了一个大的正值，并且重复的进位传播将大部分质量推入更高位。 该算法增量地处理这个问题，确保没有一个位位置在不向上标准化的情况下存储无限的大小。
