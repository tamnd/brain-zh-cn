 ## 解决方案
 ## 问题理解

 我们得到一个表示按时间顺序排列的日期序列的二进制字符串，其中每个字符要么是 0，要么是 1。我们必须将这些位置分成几个组，以便每个位置恰好属于一个组，但每个组不需要由连续的索引组成。 

每个小组必须形成“斑马序列”。 有效的斑马序列具有三个属性。 它非空，以0开始，以0结束，子序列中的相邻元素必须在0和1之间交替。 

这立即意味着每个有效子序列必须看起来像 0、01、010、0101 等，但始终以 0 结尾，因此它的长度是奇数，并且包含的 0 比 1 多一个。 

我们被要求决定这样的分区是否可能，如果可能，则输出任何有效的分区。 

输入大小最多可达 200,000 个字符，这排除了任何二次甚至二次的字符$O(n \log n)$具有大量常数，除非它的结构非常良好。 预计会出现线性或近线性贪婪构造。 

定义中隐藏着一个关键的结构约束：每个斑马都以 0 开始和结束，因此每个组都必须以既作为开始又作为结束的方式消耗零。 这已经表明零将控制可行性。 

一个天真的错误是尝试贪婪地构建子序列而不跟踪交替结构的可用性，或者独立分配零而不将它们与正确的配对。 另一个常见的失败是忽略了一个事实，即 1 必须始终位于子序列中的两个零之间。 任何不能以交替方式配对的 1 都会导致失败。 

一个小的说明性失败案例是`111000`。 总体上有足够的零和一，但是任何启动多个序列的尝试都会失败，因为没有可能以正确消耗所有 1 的方式从零开始的交替模式。 正确的输出是`-1`。 

另一个微妙的情况是`0101`。 它看起来是交替的，但它以1结尾，因此没有子序列可以完全包含它； 不可能将其分配到有效的斑马序列中。 

## 方法

 暴力方法会尝试将索引分成组并检查每个组的有效性。 这意味着将每个索引分配给可能的之一$O(n)$子序列并验证每组的交替。 即使我们将自己限制为贪婪分配，分配元素的方式数量也会呈指数增长，并且验证本身对于每个候选分区都是线性的。 这是完全不可行的$n = 2 \cdot 10^5$。 

关键的观察结果是每只斑马的结构都是刚性的。 由于序列必须交替并以 0 开头，因此每次我们放置 1 时，它都必须继续之前开始的当前以 0 结尾的序列。同样，每个 0 要么开始一个新序列，要么关闭一个期望下一个为 0 的现有序列。 

这意味着维护两个动态的“开放子序列”集：当前以 0 结尾的序列和以 1 结尾的序列。我们总是希望贪婪地匹配字符：1 必须扩展以 0 结尾的序列，而 0 必须扩展以 1 结尾的序列或开始一个新序列。 

关键的一点是，我们并不是随意选择分区；而是要选择分区。 相反，我们通过字符串有效地串接序列。 每个索引都恰好附加到一个链，并且链根据最后一个预期字符以类似堆栈的方式演变。 这将问题简化为对活动序列进行簿记的贪婪构造。 

最后，所有序列都必须以 0 结尾，这意味着任何序列都不能期望为 1。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分区| 指数| O(n) | 太慢了|
 | 贪婪链分配 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们维护两个堆栈（或列表）：一个用于当前以 0 结尾的序列，另一个用于当前以 1 结尾的序列。每个序列都由其收集的索引表示。 

1. 从左到右迭代字符串。 
2.当我们看到一个`0`，我们必须将它附加到当前以`1`如果存在这样的序列，因为它保留了交替。 如果不存在这样的序列，我们使用该索引开始一个新序列。 以 0 开始新序列是有效的，因为它们开始正确。 
3.当我们看到一个`1`，我们必须将它附加到当前以`0`。 如果不存在，施工就不可能，我们会立即失败。 
4. 连接后，我们在堆栈之间移动序列，因为它的结束字符翻转。 
5.处理完所有字符后，我们验证没有序列以`1`。 任何这样的序列都会违反所有序列都以 0 结尾的要求。 

每一步的决定都是由交替规则强制执行的。 1 不能启动 zebra，也不能跟随另一个 1，因此它总是消耗可用的“开放零端链”。 

### 为什么它有效

 在字符串的每个前缀处，每个活动序列都由其最后一个元素唯一表征。 该算法确保任何以 1 结尾的序列始终等待下一个 0，任何以 0 结尾的序列都等待下一个 1。 由于有效的斑马必须严格交替，任何偏离贪婪分配的行为只会延迟角色的消耗并降低未来的灵活性。 因为 1 只有一个有效的前驱状态（0 端序列），并且当 1 端序列存在时，0 具有永远不会降低可行性的选择，所以贪婪选择保留了所有未来的可能性。 如果在任何时候都无法分配 1，则任何重新排列都无法修复它，因为每个可以接受它的序列在结构上已经不兼容。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    zero_end = []  # sequences ending with 0
    one_end = []   # sequences ending with 1
    res = []       # list of sequences

    # each sequence is a list of indices
    for i, ch in enumerate(s, 1):
        if ch == '0':
            if one_end:
                seq = one_end.pop()
                seq.append(i)
                zero_end.append(seq)
            else:
                seq = [i]
                zero_end.append(seq)
        else:  # ch == '1'
            if not zero_end:
                print(-1)
                return
            seq = zero_end.pop()
            seq.append(i)
            one_end.append(seq)

    # all sequences must end with 0
    if one_end:
        print(-1)
        return

    print(len(zero_end))
    for seq in zero_end:
        print(len(seq), *seq)

if __name__ == "__main__":
    solve()
```该解决方案维护显式序列，并根据最后附加的字符在状态之间动态移动它们。 关键的实现细节是直接存储序列，因此最终不需要重建。 

一个微妙之处在于最终验证的处理：留在“以 1 结尾”池中的任何序列都是无效的，因为斑马必须以 0 结尾。

 ## 边缘情况

 一个关键的边缘情况是当字符串以一长串开始时，例如`11100`。 在第一个字符处，没有可附加的现有零端序列，因此算法立即拒绝输入。 这是正确的，因为斑马不能以 1 开头。 

另一种边缘情况是以 1 结尾的完美交替前缀，例如`010`。 该算法将成功构建以 1 结尾的序列，但最终验证失败，因为斑马必须以 0 结尾。这说明了为什么最终状态检查至关重要，并且不能在构建过程中用本地检查代替。 

第三种情况是多个竞争序列，例如`000111000`。 该算法根据需要创建多个链，每个 1 消耗不同的开放零端序列。 这里的正确性来自于这样一个事实：除非结构允许，否则我们永远不会将两个 1 强制放入同一链中。
