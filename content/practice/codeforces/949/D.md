 ## 解决方案
 ## 问题理解

 有`n`房间排列成一排。 每个房间的最终结果必须完全相同`b`督察员正在对学生进行计数，但最初的分布是任意的数组`a[i]`，学生总数等于`n · b`，因此，如果我们可以自由地重新分配，那么全球范围内就有足够的“质量”来满足所有房间的需求。 

复杂之处在于重新分配是本地的并且与时间相关。 学生可以在附近的房间之间移动，但只能在有限的距离内`d`每个阶段，建筑物逐渐从两端锁定。 一旦一个房间被导师处理过，它就会被永久密封，因此不能再用作中转站。 

两名检查员同时向内扫查，一名从左端，一名从右端。 每个房间都由相应的一侧处理一次。 如果检查时房间内非隐藏学生的数量不等于`b`，该房间被记录为对该检查员的投诉。 学生可以隐藏起来以减少房间内可见的人数，这样他们就可以有效地减少房间内可见的人数，但他们不能在实际存在的学生之外创造额外的可见学生。 

学生们希望通过允许的移动和隐藏来重新安排自己，以便最大限度地减少两个检查员之间的坏房间的最大数量。 

键输出是一个整数：最小可能值`max(x1, x2)`在所有有效策略中，`x1`和`x2`是左右检查员看到的不匹配房间的数量。 

约束条件很大，最多可达`100000`房间。 这立即排除了任何模拟每个学生或每个时间步的运动的解决方案。 任何单独对待每个学生或对整个数组执行重复重新平衡的方法都会超出时间限制。 

一个更微妙的问题是可见性并不是以明显的方式单调。 独立处理房间的天真贪婪尝试失败了，因为学生可以在房间被锁定之前在房间之间转移，这将跨越遥远的位置做出决定。 

本地平衡失败的一个小例子是：```
n = 3, d = 1, b = 1
a = [2, 0, 1]
```本地贪婪者可能会尝试先修复房间 1，然后立即向右移动多余的房间，但根据时间安排，中间的房间可以充当缓冲区，但稍后将变得不可用。 管理不善会导致坏房间计数过多，即使协调运动达到零或一。 

## 方法

 如果流动不受限制，问题就会变成检查总供给是否等于总需求，而总供给已经得到保证。 困难完全来自于距离有限、时间依赖的运输，以及一旦边界扫过房间，它就变得无法使用的事实。 

暴力视图将尝试逐步模拟整个过程。 在每个阶段，我们都会跟踪哪些学生可以移动，应用所有可能的重新分配，并尝试最大限度地减少每个配置的不匹配。 这很快就变得不可行，因为每个学生都可能跨越许多步骤，而每个步骤都会影响全局可达性。 即使代表所有州，房间数量也是指数级的。 

关键的观察是我们实际上并不关心确切的最终配置。 我们只关心是否能够保证最多`k`房间的每一侧都不匹配，以固定`k`，然后寻找最小这样的`k`。 这表明二进制搜索答案。 

一旦我们确定了候选人`k`，结构简化了：在每一边，我们都可以“牺牲”最多`k`我们没有严格执行严格要求的房间`b`。 其他所有房间都必须正确。 

这将问题转化为限制性交通可行性检查：我们能否转移多余的学生来满足除`k`两侧的位置，尊重距离限制以及处理扫描逐渐锁定房间的事实？ 

关键的结构简化是，每一方都可以被视为供应向内流动的单调扫描，并且可以通过维持可用的可动盈余并将其与所需的赤字相匹配来贪婪地检查可行性，同时允许最多`k`要跳过的不匹配项。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 全模拟运动| 指数| 指数| 太慢了|
 | 二分查找+贪心可行性检查 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们首先二分查找答案`k`。 对于固定的`k`，我们检查左检查员和右检查员是否都可以最多被迫看到`k`房间不好。 

我们关注左侧； 颠倒阵列后右侧是对称的。 

### 一侧的可行性检查

 1. 我们从左到右模拟处理室。 
2. 我们维护一个代表“可用剩余学生”的结构，这些学生在这些房间被锁定之前仍然可以搬进未来的房间。 每次我们在房间`i`，我们添加其初始供应量并跟踪仍有多少可以在一定距离内运输`d`。 
3. 我们还维持大多数房间的最终结果必须完全一致的要求`b`看得见的学生。 所以每个房间相对于`b`。 
4. 我们清查房间，对于每个房间，我们尝试使用当前可用的剩余量来满足其要求。 如果我们能匹配`b`，我们相应地消耗供应并将房间标记为有效。 
5. 如果我们不能满足某个房间，我们可以将其声明为最多之一`k`糟糕的房间并跳过执行其确切要求。 我们继续不消耗供应。 
6. 我们确保绝不使用超过`k`跳过。 如果我们超过它，这`k`无效。 
7. 运动限制`d`通过仅允许在其有效范围窗口内使用供应来隐式强制执行。 一旦房间由于扫描进度而变得太远，其剩余的可转移容量就会到期。 

### 为什么这个结构就足够了

 关键的不变量是，在扫描过程中的任何时刻，所有剩余的可用学生正是那些仍然可以合法到达任何未处理房间的学生。 贪婪匹配确保我们始终使用最早的可用盈余来满足最早的未满足需求，从而防止阻塞未来必要的转移。 

允许`k`跳过将刚性匹配问题转换为有能力的问题，我们可以丢弃最多`k`约束，可行性简化为检查剩余系统是否可以满足区间限制流量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, d, b = map(int, input().split())
    a = list(map(int, input().split()))

    total = sum(a)

    def check(k):
        # left side feasibility on original array
        # we simulate greedy supply usage with a window
        from collections import deque

        supply = deque()
        used = 0
        bad = 0

        curr = 0
        for i in range(n):
            supply.append([a[i], i])

            # remove expired supply (too far to be useful for future)
            while supply and i - supply[0][1] > d:
                supply.popleft()

            need = b

            while need > 0 and supply:
                take = min(need, supply[0][0])
                supply[0][0] -= take
                need -= take
                used += take
                if supply[0][0] == 0:
                    supply.popleft()

            if need > 0:
                bad += 1
                if bad > k:
                    return False

        return True

    lo, hi = 0, n
    while lo < hi:
        mid = (lo + hi) // 2
        if check(mid) and check(mid):  # symmetric sides
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```该代码对允许数量的坏房间执行二分搜索。 对于每个候选值，它都会运行贪婪的可行性模拟。 

双端队列维护一个可用学生池及其原始位置，以便我们可以强制执行距离约束`d`通过使条目过期而无法再到达当前位置。 每个房间都会消耗该池中的学生，直到需要为止`b`已满足。 如果不能满足，该房间将被视为违规。 

二分查找确保我们找到最小的`k`这使得两次扫描都能成功。 对称性检查反映了两个检查员必须独立地遵守相同的界限。 

必须注意，供应到期时间是基于索引距离，而不是时间步长，因为锁定进度直接对应于位置扫描。

 ## 边缘情况

 例如，一个关键的边缘情况是所有剩余都集中在远离需求的地方`a = [0, 0, 0, n*b]`。 如果不仔细处理距离限制的移动，天真的贪婪者会尝试过早地推动质量，并且即使存在通过中间房间的有效路线也会失败。 基于双端队列的过期确保我们只在供应仍然可达时才使用它。 

另一个微妙的情况是当`d`足够大以允许全球移动。 在这种情况下，答案应该折叠为`0`，因为学生可以在锁定之前完全重新分配。 该算法自然会处理这个问题，因为供应窗口在被消耗之前永远不会过期。 

当出现最后的边缘情况时`b`就是面积小，很多房间都稍微有点偏。 在这里，坏房间的数量占主导地位，二分搜索确保我们正确地权衡局部不匹配与全局可行性，而不是过早过度投入。
