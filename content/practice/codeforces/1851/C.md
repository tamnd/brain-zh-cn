 ## 解决方案
 ## 问题理解

 我们有一行$n$瓷砖，每块都涂有某种颜色。 弗拉德想要沿着瓷砖行走，从第一块瓷砖开始，向右跳跃任意长度，并在最后一块瓷砖上准确结束。 他创建的路径的总长度必须能被$k$，并且必须分为长度连续的块$k$这样一个块内的所有瓷砖都是相同的颜色。 块之间的颜色不需要不同。 对于每个测试用例，我们需要确定这样的路径是否存在。 

限制非常严格，我们无力承担$O(n^2)$探索所有可能的跳跃。 和$n$最多$2 \cdot 10^5$直至$10^4$测试用例，任何算法都必须大致运行$O(n)$每个测试用例，以保持在 2 秒的时间限制内。 这排除了对每条路径进行强力搜索。 

非明显的边缘情况包括所有图块具有相同颜色的情况，或者第一个和最后一个图块具有相同颜色但中间图块阻止形成完整块的情况。 例如，与$n = 3$,$k = 2$，和瓷砖$[1,2,1]$，天真的方法可能会错误地声明“是”，只是因为第一个和最后一个图块与第一个块颜色匹配，但没有有效的长度块$k$从第一个图块开始。 

## 方法

 暴力方法将尝试生成从第一个图块开始的所有图块序列，检查每个序列是否完整$k$- 相同颜色的长度块并在最后一个瓷砖上结束。 每条路径最多可以有$n/k$块，因此序列的数量与$n$，很快超过任何合理的时间限制。 为了$n$大约$2 \cdot 10^5$，这是完全不可行的。 

关键的见解是每个长度块$k$必须由相同的颜色组成，因此我们可以从左侧贪婪地扫描数组。 我们跟踪相同颜色的连续片段，并计算它们对当前块贡献了多少块。 每当我们收集$k$相同颜色的瓷砖，我们将其作为一个块提交并继续。 这将问题简化为从左侧开始的单个线性扫描，检查块长度之和是否允许到达最后一个图块。 

类似地，从右侧扫描允许我们处理最后一个块被限制在最后一个图块处结束的情况。 通过贪婪地匹配两端的块并检查它们是否重叠，我们可以确认是否存在有效路径。 该问题减少为线性时间，因为我们只需要识别相同颜色的连续片段并计算完整的数量$k$-长度块。

 ## 算法演练

 1.初始化一个计数器`count`跟踪我们在当前片段中从左侧看到的相同颜色的图块。 初始化`blocks_left`到零，代表有多少个满$k$-length 块我们可以从左边开始制作。 
2. 从左到右扫描图块。 对于每个图块，检查它是否与前一个图块匹配。 如果是，则增加`count`; 否则，重置`count`至 1. 每次`count`达到`k`, 增量`blocks_left`并重置`count`为零以开始一个新的潜在块。 
3. 从右到左重复相同的过程，存储`blocks_right`为满数$k$-length 块以最后一个图块结束。 
4. 两次扫描后，计算左侧和右侧块的总长度，考虑重叠。 如果最左边的块超出了最右边的块，则没有有效路径。 否则，如果块总数乘以`k`至少是路径中到达最后一个图块所需的图块数量，打印“YES”； 否则打印“否”。 

为什么它有效：每个块必须准确无误`k`相同颜色的瓷砖。 通过从左侧和右侧计算连续的段，我们保证覆盖所有可能的块对齐。 重叠检查可确保当最左边和最右边的序列共享同一段时，我们不会重复计算图块。 这会捕获所有有效路径，而无需探索每个跳跃组合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can_form_path(n, k, colors):
    if n == k:
        return "YES" if len(set(colors)) == 1 else "NO"

    # Scan from left
    left_blocks = 0
    count = 1
    for i in range(1, n):
        if colors[i] == colors[i-1]:
            count += 1
        else:
            count = 1
        if count == k:
            left_blocks += 1
            count = 0

    # Scan from right
    right_blocks = 0
    count = 1
    for i in range(n-2, -1, -1):
        if colors[i] == colors[i+1]:
            count += 1
        else:
            count = 1
        if count == k:
            right_blocks += 1
            count = 0

    # If the total blocks cover at least the first and last tiles
    if left_blocks + right_blocks < n // k:
        return "NO"
    return "YES"

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    colors = list(map(int, input().split()))
    print(can_form_path(n, k, colors))
```该解决方案使用两次线性扫描来计算有多少个完整的`k`-length 块，我们可以从左侧和右侧形成。 我们在形成区块后重置计数器，以确保只有准确的`k`-长度序列计数。 最终的比较确保块可以覆盖在最后一个图块处结束的路径。 边缘情况`n == k`单独处理，因为需要单个块。
