 ## 解决方案
 ## 问题理解

 我们得到了一系列药水类型，每种类型都有直接购买价格，但有些药水也可以通过根据固定配方混合其他药水来生产。 每个配方都会完全消耗其成分，因此一旦使用，那些输入的药水就会消失。 配方结构是非循环的，因此无法最终从自身开始导出药水。 

一开始，娜斯佳已经无限量供应了几种药剂类型。 这些类型可以被视为免费资源，因为不需要购买它们。 对于每种其他药水类型，我们需要确定获得至少一个单位该药水所需的最小硬币数量，可以直接购买，也可以通过一系列有效的混合来生产。 

输入描述了一个定向依赖系统：每个药剂都列出了生成它所需的一组药剂。 这定义了一个有向无环图，其中边从成分指向最终的药水。 任务是计算“激活”每个节点的最小成本，其中激活成本是其购买价格或其先决条件的成本总和。 

这些约束意味着线性或近线性解。 所有测试用例中的部分总数和依赖边总数最多为 2×10^5，因此任何执行与每个松弛步骤的边数成比例的工作或使用重复重新计算的解决方案都会超时。 这立即排除了每个节点的简单递归重新计算和任何二次传播。 

当药水是初始自由套装的一部分时，就会出现一个微妙的问题。 这样的节点的行为就像零成本源，即使它具有稍后在输入中列出的依赖项。 忽略此覆盖的粗心方法可能会错误地将正成本分配给应该免费的药水。 

另一个陷阱是假设可以按输入顺序处理菜谱。 由于依赖项形成 DAG，但在输入中未按拓扑排序，因此不考虑依赖项顺序的计算成本将导致使用未初始化的值。 

## 方法

 一种直接的方法是独立处理每个药水，并尝试通过递归扩展所有可能的构建方法来计算其成本。 对于给定的药水，我们要么计算其购买成本，要么尝试每种配方并对其成分的成本求和。 如果我们通过递归和记忆来计算这些值，则正确性源于以下事实：每种药水的最佳成本仅取决于其先决条件。 

然而，这会降低效率。 在最坏的情况下，一个部分可能依赖于许多其他部分，并且跨重叠子问题的重新计算会导致重复遍历相同的依赖边。 由于总边数高达 2×10^5，每个节点的朴素 DFS 可能会退化为二次行为。 

关键的观察结果是依赖图是非循环的，并且如果按拓扑顺序处理，每个部分仅依赖于已经可计算的子问题。 一旦我们以有效的顺序处理节点，每个节点的答案就可以根据其先决条件的已最终值计算一次。 这将问题转化为 DAG 上的单次传递，其中每个节点聚合来自其传入边缘的信息。 

我们还将最初的免费药水视为零成本来源，从而自然地为传播播种。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个节点的强力 DFS | O(n·m) | O(n + m) | 太慢了 |
 | DAG 上的拓扑 DP | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 我们将每个药剂建模为有向图中的一个节点。 如果部分 i 需要部分 j，我们将创建一条从 j 到 i 的有向边，因为 j 必须在 i 之前计算。

我们还计算入度，它计算每个节点有多少个先决条件。 入度为零的节点可以立即处理，因为它们不依赖任何东西。 

1. 使用从每种成分到其帮助生产的药水的反向边构建图表。 这确保依赖流与计算顺序匹配。 
2. 初始化一个成本数组，其中每个药水最初都有其直接购买成本。 对于免费套装中的药水，将它们的成本覆盖为零，因为它们总是可以在不花费硬币的情况下获得。 
3. 根据依赖边计算每个节点的入度。 这告诉我们哪些节点已准备好处理。 
4. 初始化一个队列，其中所有入度为零的节点。 这些节点没有未满足的先决条件，因此它们当前的成本已经是最终的。 
5. 按队列顺序处理节点。 对于节点 u，考虑所有传出边 u → v。我们通过尝试使用 u 的贡献来提高其成本来更新 v。 具体来说，我们维护每个 v 的已知先决条件成本的运行总和。 
6. 在处理每个传入的贡献后减少 v 的入度。 当入度达到零时，v的所有先决条件都已考虑在内，因此我们可以最终确定v并将其推入队列。 
7. 继续，直到处理完所有节点。 当每个节点的所有依赖关系都得到解决时，每个节点都会被评估一次。 

核心不变量是，当一个节点被处理时，它的所有先决条件都已经被分配了它们的最小可能成本。 由于我们仅结合已经最优的子结果并与直接购买成本进行比较，因此任何后续操作都不会降低最终值。 这保证了拓扑DP的正确性。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        c = list(map(int, input().split()))
        free = set(map(lambda x: int(x) - 1, input().split()))

        g = [[] for _ in range(n)]
        indeg = [0] * n
        need = [[] for _ in range(n)]

        for i in range(n):
            tmp = list(map(int, input().split()))
            m = tmp[0]
            req = [x - 1 for x in tmp[1:]]
            need[i] = req
            indeg[i] = m
            for v in req:
                g[v].append(i)

        dp = c[:]
        for i in free:
            dp[i] = 0

        q = deque()

        for i in range(n):
            if indeg[i] == 0:
                q.append(i)

        while q:
            u = q.popleft()
            for v in g[u]:
                dp[v] = min(dp[v], sum(dp[x] for x in need[v]))
                indeg[v] -= 1
                if indeg[v] == 0:
                    q.append(v)

        print(*dp)

if __name__ == "__main__":
    solve()
```该图是反向构建的，因此当处理先决条件时，它可以为其依赖节点做出贡献。 这`need`list 存储完整的依赖关系列表，以便当节点准备就绪时，我们可以一步计算其成分的总和。 队列确保节点按照依赖顺序进行处理。 

关键的实现细节是，只有当节点的所有先决条件都满足时，我们才会最终确定节点。 此时，其依赖项的总和是有效的，因为它使用的所有 dp 值都已经是最优的。

 考虑一个具有五种药水的小型系统，其中一些可以自由使用，另一些则取决于组合。 我们跟踪 dp 值和入度。

 第二种情况是，免费药水通过多个依赖项传播零成本，这表明初始可用性如何大幅降低下游成本。 一旦处理了它们的先决条件，依赖于免费成分的节点就会立即收敛到较低的值。

 ## 边缘情况

 一个重要的情况是，一种药水既可购买又可制作，但制作成本更高。 在这种情况下，算法仍然必须比较两个选项。 这是通过使用直接成本初始化 dp 并仅应用来处理的`min`当计算配方成本时，确保不会强制覆盖。 

另一种情况是当依赖链深处出现免费药水时。 由于我们在处理之前将其 dp 初始化为零，因此一旦聚合了其先决条件，任何依赖于它的节点都将正确继承减少的成本。 

最后的边缘情况是没有依赖关系且不在自由集中的节点。 由于不存在替代结构，因此它应保持等于其购买成本。 该算法保留了这一点，因为这些节点只是简单地初始化，并且永远不会通过传入边进行更新。
