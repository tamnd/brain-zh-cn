 ## 解决方案
 ## 问题理解

 我们有两个整数数组，一个属于 Devu，另一个属于他的兄弟。 我们可以在一次操作中重复将任一数组的任何单个元素增加或减少 1。 目标是使用最少数量的此类单位调整来转换数组，使 Devu 数组中的最小值至少与其兄弟数组中的最大值一样大。 

解释该条件的一个有用方法是，我们需要一个阈值，使得第一个数组中的每个元素都至少为该阈值，而第二个数组中的每个元素最多为该阈值。 最终阈值不是预先固定的，它是由我们选择修改两个数组的方式隐式确定的。 

这些约束允许每个数组最多包含 100,000 个元素，值最大为 1e9。 任何试图逐步模拟操作的解决方案都是立即不可能的，因为在最坏的情况下，即使是单个调整序列也可能需要数十亿步。 这促使我们寻求一种在接近线性或线性运算时间内工作的解决方案，可能涉及排序和某种形式的贪婪结构或对候选阈值的二分搜索。 

当尝试独立修复两个阵列而不协调它们时，会出现一个幼稚的错误。 例如，人们可能会尝试将所有元素推入`a`达到其最小可行值并推动所有元素`b`降低到其最大可行值，而不考虑最佳会面点可能会随着调整的发生而变化。 如果我们假设我们应该只移动，就会发生另一个微妙的失败`a`向上或仅移动`b`向下，因为在某些情况下，稍微调整两侧比仅大幅修改一侧便宜。 

考虑一个简单的场景：`a = [1, 100]`,`b = [50]`。 如果我们只提高`a`，我们需要提高`1`至少到`50`，花费 49。如果我们也减少`b`或者小心地改变门槛，我们可能会降低总成本。 这说明最佳解决方案取决于全局阈值而不是独立修复。 

## 方法

 暴力方法将尝试最终阈值的所有可能值。 对于固定阈值`x`，我们计算制造每一个的成本`a[i] >= x`和每一个`b[j] <= x`。 对于每个元素，成本就是它距约束的距离：如果`a[i] < x`，我们支付`x - a[i]`，否则为 0； 如果`b[j] > x`，我们支付`b[j] - x`，否则为 0。将这些相加得出该阈值的成本。 

这是正确的，因为一旦目标阈值固定，每个元素都可以独立调整，无需交互。 然而，尝试 1 到 1e9 之间的每个可能的整数是不可能的。 

关键的观察结果是成本函数在阈值方面是凸的。 当我们提高门槛时，成本`a`而成本则增加`b`以结构化的方式减少。 这意味着最佳值出现在由现有数组值形成的“临界点”附近。 事实上，只考虑以下值中的候选阈值就足够了`a`和`b`，因为在连续的排序值之间，成本函数的斜率不会改变。 

一旦我们对两个数组进行排序，我们就可以使用前缀信息有效地评估所有候选阈值，或者我们可以通过将其转换为经典的中值样式对齐问题来进一步减少问题。 最简洁的解释是在概念上围绕一个枢轴合并两个数组，并找到一个平衡的分割，最大限度地减少向共享边界的总绝对移动。 

更直接的最优见解是我们要选择一个值`x`这样我们就可以最小化：

 以下要素所需增加的总和`x`在`a`，加上上述元素所需的减少`x`在`b`。 排序使我们能够在每个候选者的线性时间内增量地评估这些贡献，甚至使用两个指针进行摊销常数时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力战胜一切 x | O(N * 最大值) | O(1) | O(1) | 太慢了|
 | 排序+扫描/两个指针| O((n + m) log(n + m)) | O((n + m) log(n + m)) | O(1) 额外（除了排序） | 已接受 |

 ## 算法演练

 我们首先对两个数组进行排序，以便我们可以以结构化的方式推断阈值。 排序后，我们将潜在答案视为位于现有元素或现有元素之间的值。 

然后，我们通过扫描满意元素和不满意元素之间的“活动边界”发生变化的可能位置来评估候选阈值。 

1. 数组排序`a`和数组`b`。 需要进行排序，以便元素按顺序跨越阈值，从而允许增量成本跟踪。 
2. 初始化代表当前阈值位置和两侧调整元素成本的指针和累加器。 
3. 考虑从两个数组导出的位置，向上扫描阈值。 在每一步中，维护有多少个元素`a`低于阈值以及有多少元素`b`都在它之上。 
4. 将阈值从一个候选值移至下一个候选值时，增量更新成本，而不是从头开始重新计算。 变化仅取决于间隔内有多少元素受到影响。 
5. 跟踪所有评估阈值的最低成本。 

重要的想法是，在两个连续的候选值之间，哪些元素对成本有贡献的结构不会改变，因此成本线性演变并且可以在恒定时间内更新。 

### 为什么它有效

 在任何固定阈值下，每个元素根据其与阈值的关系独立做出贡献。 这使得总成本成为分段线性函数的总和。 排序可确保提前知道这些函数的所有断点。 由于成本的导数仅在数组值处发生变化，因此最小值必须出现在这些断点之一处。 通过仅评估这些点，我们保证不会跳过任何最佳解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    a.sort()
    b.sort()
    
    # prefix sums for fast range cost computation
    pa = [0]
    for x in a:
        pa.append(pa[-1] + x)
    
    pb = [0]
    for x in b:
        pb.append(pb[-1] + x)
    
    def cost(x):
        # cost to make all a[i] >= x
        import bisect
        i = bisect.bisect_left(a, x)
        cost_a = x * i - pa[i]
        
        # cost to make all b[j] <= x
        j = bisect.bisect_right(b, x)
        cost_b = (pb[m] - pb[j]) - x * (m - j)
        
        return cost_a + cost_b
    
    # candidate points are values in a and b
    candidates = set(a + b)
    
    ans = float('inf')
    for x in candidates:
        ans = min(ans, cost(x))
    
    print(ans)

if __name__ == "__main__":
    solve()
```代码首先对两个数组进行排序，以便我们可以计算前缀和并快速评估成本。 这`cost(x)`函数使用二分搜索将每个数组分成两部分：低于或高于阈值的元素。 为了`a`，我们计算需要多少来提高较小的元素。 为了`b`, we compute how much we need to lower larger elements.

 We then evaluate only candidate thresholds drawn from existing values. 这是有效的，因为在两个相邻的排序值之间，没有元素改变其贡献类型，因此成本函数是线性的，并且在区间内不能有新的最小值。

 ## 边缘情况

 当所有元素`a`已经大于所有元素`b`。 在这种情况下，条件已经满足，答案应该为零。 该算法自然地处理这个问题，因为对于范围之间的任何候选阈值，没有元素违反条件，从而产生零成本。 

当数组严重交错时会出现另一种边缘情况，例如`a = [1, 100, 200]`和`b = [50, 60, 70]`。 最佳阈值位于两个阵列贡献部分成本的重叠区域内。 对候选值的扫描可确保捕获该区域内的最小值。 

最后一个微妙的情况是最佳阈值位于值之间而不是恰好位于某个值处。 尽管我们只测试离散候选者，但成本函数在连续排序值之间是线性的，因此任何内部最小值都意味着端点共享相同的成本，这意味着评估端点就足够了。
