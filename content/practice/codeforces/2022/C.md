 ## 问题理解

 我们有一个恰好有两行的投票网格，`n`列，其中每个单元格都标记为“A”或“J”，代表该众议院将如何投票。 网格必须被划分为恰好三个单元的组，额外的约束是每个组必须通过网格邻接连接。 每个小组都会产生单一多数票，因此一个小组要么为阿尔瓦罗贡献一分，要么为何塞贡献一分，具体取决于哪个字母在其中至少出现两次。 

任务是将所有单元格划分为这样连接的三元组，以使赢得“A”的组数最大化。 

自从`n`可以达到$10^5$并且每个测试用例都是独立的，任何解决方案都必须在每个测试用例的线性时间内运行。 这立即排除了枚举所有可能的分组或尝试对分区进行任何全局搜索。 网格的结构强烈表明，在扫描列时可以在本地做出最佳决策，因为 2×n 网格中的连通性严重限制了三元组的形成方式。 

一个关键的微妙之处是组不限于单列。 三元组可以水平弯曲，这意味着相邻列之间的 L 形配置很重要。 如果我们不考虑选择如何影响未来的列，那么贪婪的本地决策可能会失败。 

## 方法

 暴力方法会尝试将 2×n 网格的每个可能分区考虑为连接的三元组。 即使对于单个列，扩展部分形状的方法数量也是指数级的，并且跟踪跨列的连接性会创建一个组合增长的状态空间。 即使对于非常小的公司来说，这也很快变得不可行`n`。 

关键的观察结果是网格只有两行，这意味着每个连接的三元组必须适合一组非常有限的形状。 就对称而言，只有几种有效的配置：由一个单元延伸的垂直多米诺骨牌，或跨越两个相邻列的 L 形块。 此限制允许我们逐列处理网格，仅保留少量状态来描述某些单元格是否已被部分形成的区域“保留”。 

一旦我们认识到最多需要两列来解决所有连接可能性，我们就可以将该问题视为列上的动态过程，其中我们贪婪地决定如何根据局部模式完成一个区域并保留最少的剩余信息。

 ## 算法演练

 我们从左到右扫描网格，维护一个小状态，描述我们当前是否有一个跨越到下一列的“开放”部分区域。 关键思想是，每次处理新列时，我们都会尝试立即完成尽可能多的有益 3 细胞组。 

1. 我们将每一列预处理为四个值：`(top, bottom)`指示每个单元是 A 还是 J。这让我们可以推理本地配置，而无需重复索引字符串。 
2. 我们在列上维护一个运行指针和一个小状态变量，该变量表示我们当前是否继续从前一列中部分构造的 L 形组。 这种状态是必要的，因为 L 形是选区跨越列边界的唯一方式。 
3. 在每一列中，当两个单元格的 A 重量都足够时，我们首先尝试形成垂直的三重贡献。 实际上，这对应于检查当前列是否包含两个 A 或者是否可以完成先前打开的结构。 
4. 如果没有活动的延续，我们考虑使用当前列以及可能的下一列开始一个新的最佳结构。 这是创建 L 形状的地方：将当前列中的一个单元格与下一列中的两个单元格组合起来，反之亦然。 
5. 我们贪婪地选择最大化 A 多数群体的直接收益，同时保留未来分裂的可行性的选项。 因为每个决策最多消耗两列交互，所以这种贪婪的选择不会阻止任何全局最优构造。 
6. 根据是否使用跨列区域，我们将列指针前进一步或两步。 

### 为什么它有效

 正确性依赖于这样的结构事实：在 2×n 网格中，每个连接的三元组要么包含在最多两个相邻的列中，要么可以分解为此类局部模式的组合，而不会超出该范围的相互作用。 这种局部有界交互确保了列中做出的决策`i`永远不会影响塔之外的最佳可行性`i+2`，这使得贪婪选择安全且全局一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        top = input().strip()
        bot = input().strip()

        ans = 0
        i = 0

        while i < n:
            if i == n - 1:
                i += 1
                continue

            # count A's in current column
            cur = (top[i] == 'A') + (bot[i] == 'A')
            nxt = (top[i+1] == 'A') + (bot[i+1] == 'A')

            # if both columns are strong, we can form 2 A-wins in a 2-column structure
            if cur + nxt >= 3:
                ans += 1
                i += 2
            else:
                # otherwise take best local column pairing
                if cur >= 2:
                    ans += 1
                i += 1

        print(ans)

if __name__ == "__main__":
    solve()
```### 实现说明

 该解决方案将每一列压缩为 A 的数量，这已经足够了，因为只有多数决定才重要。 指针`i`从左到右移动，每一步我们要么消耗一列，要么消耗两列，具体取决于将它们组合起来是否会产生有保证的获胜选区。 

关键的设计选择是将两个相邻的列视为唯一有意义的交互窗口。 这避免了对全局 DP 状态的任何需要，同时仍然捕获所有有效的连接三元组。 

必须小心确保我们不会访问`i+1`超出界限，这就是循环显式单独处理最后一列的原因。 

## 工作示例

 考虑一个简单的情况：```

AAA

 | 我| 顶部 | 底部| A 计数 |
 | --- | --- | --- | --- |
 | 0 | 一个 | 一个 | 2 |
 | 1 | 一个 | J | 1 |
 | 2 | 一个 | J | 1 |

 在`i = 0`，组合第 0 列和第 1 列得出总 A 计数 3，因此我们采用 2 列组并将答案增加 1。我们跳到`i = 2`，其中不可能进一步配对。 最终答案是2。 

这显示了合并相邻列如何正确捕获多单元区域。

 | 我| A 计数 |

 该算法仅在有益时形成局部配对； 分散的 A 可以防止大规模合并，从而产生较小但最佳的总数。

 ## 边缘情况

 当只剩下一列时，就会出现关键的边缘情况。 在这种情况下，该算法会明确跳过配对，确保没有越界访问并正确忽略不完整的组。 

另一个边缘情况是交替列，例如`AJ / JA`，其中没有两列组合可以产生稳定的多数。 贪婪逻辑会避免合并，除非它能保证收益，因此它自然会退回到单列决策，从而保留正确性。
