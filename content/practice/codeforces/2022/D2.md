 ## 问题理解

 任务是找出其中唯一的冒名顶替者$n$互动游戏中的玩家，每个玩家都扮演三个角色之一：骑士、无赖或冒名顶替者。 骑士总是说真话，无赖总是撒谎，而冒名顶替者从其他人的角度来看，表现得像无赖。 我们可以提出“玩家是否$i$思考玩家$j$是骑士？”并收到二进制响应。目标是在正确识别冒名顶替者的同时最大限度地减少提出的问题数量。

 输入提供每个测试用例的玩家数量，并通过查询执行交互。 自从$n$可以达到$10^5$和总和$n$所有测试用例的总和是$10^5$，任何直接查询所有对的算法都需要$O(n^2)$操作，速度太慢。 这排除了暴力枚举。 因此，挑战不仅在于正确性，还在于效率。 

一种简单的方法可能会查询每个玩家的其他玩家的信息，以便对他们进行单独分类，但允许的最大查询次数远远少于$n^2$。 边缘情况包括只有一名骑士或只有一名无赖的配置，其中天真的成对查询可能会错误地识别冒名顶替者。 例如，对于三个玩家，如果玩家 1 和 2 是无赖，而玩家 3 是冒名顶替者，那么粗心的查询可能会给出与其他分布无法区分的答案，因此需要对问题进行策略性选择。 

## 方法

 蛮力方法是向每个玩家询问其他每个玩家的情况，然后使用完整的响应矩阵来推断角色。 虽然原则上是正确的，但这需要$O(n^2)$查询，这对于$n$最多$10^5$。 

减少查询的关键见解来自于我们只需要识别一个骑士或一对玩家的观察，他们的答案可以揭示一致性。 一旦找到骑士，就可以查询该玩家的所有其他玩家，以有效地对其他所有人进行分类。 因此，最小策略包括迭代地比较成对的玩家并消除冒名顶替者的候选者，直到孤立出一个骑士，然后与该骑士执行线性扫描以找到冒名顶替者。 

这将查询数量减少到$O(n)$，因为每个查询要么消除一个候选，要么提供一个明确的分类。 问题结构——只有一个冒名顶替者存在并且骑士的答案是可靠的——允许这种减少。 

| 方法| 时间复杂度| 空间复杂度| 判决|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n²) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从完整的球员名单开始$1$到$n$。 维护一个可能是冒名顶替者的候选索引。 
2. 比较连续的玩家对$(i, i+1)$通过询问$i$关于$i+1$。 如果答案是“是”，则保留一名候选人，否则保留另一名候选人。 每次比较都会消除一个潜在的冒名顶替者或提供有关骑士的信息。 
3. 线性扫描后，留下一名候选者。 向该候选人询问所有其他玩家的情况。 如果响应表明玩家是骑士，请相应地标记他们。 
4. 从这些结果中识别出已确认的骑士。 已确认的骑士用作参考：向他们查询所有剩余的未知玩家。 
5. 确认骑士回答“否”的玩家是冒名顶替者。 将该玩家输出为冒名顶替者。 

这种方法之所以有效，是因为候选消除可以确保至少有一个 Knight 在线性扫描中幸存下来，并且 Knights 的答案是可靠的。 一旦确认了骑士，他们的答案就会对所有剩余玩家进行明确的分类，从而最多可以识别冒名顶替者$2n$查询。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
def flush():
    sys.stdout.flush()

def query(i, j):
    print(f"? {i} {j}")
    flush()
    return int(input())

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        candidate = 1
        # Step 1: find a candidate
        for i in range(2, n+1):
            res = query(candidate, i)
            if res == 0:
                candidate = i
        # Step 2: find a confirmed Knight
        knight = None
        for i in range(1, n+1):
            if i == candidate:
                continue
            res = query(i, candidate)
            if res == 1:
                knight = i
                break
        # Step 3: identify Impostor
        for i in range(1, n+1):
            if i == knight:
                continue
            res = query(knight, i)
            if res == 0:
                print(f"! {i}")
                flush()
                break

if __name__ == "__main__":
    solve()
```第一个循环通过在每一步消除一个玩家来识别冒名顶替者的候选人。 第二个循环通过查询所有其他人有关候选人的信息来找到骑士。 一旦知道了某个骑士，他们的反应就保证可靠，并且我们向他们询问所有剩余的未知数。 骑士回答“不”的玩家是冒名顶替者。 

## 工作示例

 对于`n=4`与玩家角色`[Knight, Knave, Impostor, Knave]`，该算法按顺序比较候选者。 假设候选人从玩家 1 开始：

 | 候选人| 下一页 | 回应 | 新候选人 |
 | --- | --- | --- | --- |
 | 1 | 2 | 0 | 2 |
 | 2 | 3 | 0 | 3 |
 | 3 | 4 | 1 | 3 |

 候选人 3 幸存。 询问其他人以找到骑士。 玩家 1 对 3 说“是”→ 玩家 1 是骑士。 查询 Knight 1 的所有信息：只有候选人 3 得到“否”，因此 Impostor 是 3。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个玩家最多被查询两次：一次在候选扫荡中，一次被确认的 Knight |
 | 空间| O(1) | O(1) | 仅存储常量变量和索引 |

 这种线性复杂性确保了可行性$n$最多$10^5$并且符合2s的限制。

 ## 边缘情况

 对于最小的情况`n=3`有角色`[Knight, Knave, Impostor]`，候选人淘汰立即识别出冒名顶替者。 如果最后询问骑士，他们的答案仍然保证正确识别冒名顶替者。 对于最大情况`n=10^5`，该算法随玩家数量线性扩展，查询策略确保在对冒名顶替者进行分类之前始终找到骑士，从而防止由于答案不一致而导致错误识别。
