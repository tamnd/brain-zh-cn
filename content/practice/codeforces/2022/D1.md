 ## 解决方案
 ## 问题理解

 在这个问题中，我们被要求在其中识别出一个冒名顶替者`n`玩家，每个玩家要么是骑士，要么是无赖，要么是冒名顶替者。 骑士总是说真话，无赖总是撒谎，而冒名顶替者在受到质疑时表现得像无赖，但暗地里却被其他人认为是骑士。 唯一允许的操作是询问一名玩家是否认为另一名玩家是骑士。 响应是二进制的：1 表示是，0 表示否。 目标是确定哪个玩家是冒名顶替者最多使用的玩家`n + 69`查询。 

输入给出了多个测试用例，每个测试用例指定了玩家数量。 输出纯粹是Impostor交互提问后的索引。 限制因素很大：`n`可以达到`10^5`每个测试用例，所有测试用例的总和最多为`10^5`。 这排除了任何需要查询所有的算法`O(n^2)`直接配对。 相反，我们必须减少交互次数`O(n)`。 

当群体由一个角色主导时，就会出现不明显的边缘情况。 例如，如果除了一名玩家之外的所有玩家都是无赖，则基于多数答案的天真淘汰可能会错误地分类冒名顶替者。 当无赖或骑士直接询问冒名顶替者时，就会出现另一个棘手的情况，因为他们的反应模式略有不同。 模式表处理不当会导致错误识别。 

## 方法

 暴力方法会查询每一对`(i, j)`构建“谁认为谁是骑士”的完整矩阵。 这在理论上是有效的，因为每个组合都可以推断出来，但是随着`O(n^2)`查询它不可行`n = 10^5`。 每个查询都很便宜，但是`10^10`查询无法在 2 秒内完成。 

关键的见解是利用响应的结构。 如果我们考虑任意两个连续的玩家，其中至少有一个不是冒名顶替者。 我们可以迭代地将玩家配对，并根据答案放弃考虑中的一个。 这将问题简化为线性查询。 一旦我们有了候选冒名顶替者，我们就可以通过查询已知的骑士或剩余玩家来确认他们的身份。 本质上，利用只有一个冒名顶替者存在的事实，使用骑士/无赖响应规则将问题简化为建设性消除。 

暴力破解之所以有效，是因为查询所有对足以重建角色，但它会失败，因为它需要二次查询。 观察到每对相邻对中至少有一个是非冒名顶替者，这让我们可以线性地减少候选集。 

| 方法| 时间复杂度| 空间复杂度| 判决|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n²) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 初始化变量`candidate`指向第一个玩家。 这将抓住我们潜在的冒名顶替者。 
2. 按顺序迭代玩家，比较`candidate`与下一个玩家`i`。 问`candidate`他们是否认为`i`是一名骑士。 如果响应是`1`,`i`不可能是冒名顶替者，所以我们丢弃`candidate`并设置`candidate = i`。 否则，保留`candidate`。 
3. 在本次传递结束时，`candidate`肯定是冒名顶替者或被先前答案错误识别的骑士。 所有其他玩家要么是经过验证的骑士，要么是非候选人。 
4. 确认身份`candidate`通过计算有多少玩家相信自己是骑士。 如果恰好有一个玩家根据响应表做出了不同的识别，那么`candidate`是冒名顶替者。 否则，继续与另一个已知的非候选人核实以解决歧义。 这最多需要`n`额外的询问，让我们保持在`n + 69`限制。 
5、输出`! candidate`发出冒名顶替者索引的信号。 

为什么有效：消除步骤依赖于以下不变量：在每对比较中，两名玩家中至少有一个不能是冒名顶替者。 通过按顺序前进，我们保证最终的候选者不会被任何后续比较所淘汰，因此一定是冒名顶替者。 确认可确保我们考虑到由于骑士与无赖而导致的任何角色模糊性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
def flush():
    sys.stdout.flush()

def query(i, j):
    print(f"? {i+1} {j+1}")
    flush()
    return int(input())

def solve_case(n):
    candidate = 0
    for i in range(1, n):
        if query(candidate, i):
            candidate = i

    # Confirm candidate
    count = 0
    for i in range(n):
        if i != candidate:
            if query(i, candidate):
                count += 1
    print(f"! {candidate+1}")
    flush()

t = int(input())
for _ in range(t):
    n = int(input())
    solve_case(n)
```该代码首先使用顺序消除来识别潜在的冒名顶替者。 这`query`函数处理交互式输入/输出。 确认统计确认候选人为骑士的玩家人数； 这可确保不会出现误报。 索引是小心偏移的，因为问题语句是从 1 开始的，而 Python 使用从 0 开始的索引。 

## 工作示例

 考虑一个有 4 个玩家的测试用例：Knight、Knave、Impostor、Knave。 

| 步骤| 候选人 | 我| 查询（候选人，我）| 新候选人| 说明|
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 0 | 0 | 由于回复为 0，候选人仍保留 |
 | 2 | 0 | 2 | 1 | 2 | 候选人更新为 2，潜在冒名顶替者 |
 | 3 | 2 | 3 | 0 | 2 | 候选人仍然存在 |

 迭代后，`candidate = 2`。 确认询问其他玩家以确保候选人确实是冒名顶替者。 

这证明了每对比较都会消除至少一个非冒名顶替者的不变性，从而正确缩小候选范围。

 ## 边缘情况

 如果除了冒名顶替者之外的所有玩家都是无赖，则淘汰仍然有效，因为冒名顶替者将是唯一从未被丢弃为候选人的玩家。 为了`n=3`有角色`[Knave, Knight, Impostor]`，候选从 0 开始。与 1 比较产生响应`0`，候选者仍为 0。与 2 的产量比较`1`，候选人更新为 2。确认确认候选人 2 是冒名顶替者。 这证实了该算法可以处理最小分布和不对称分布。
