 **已验证：** 否

 ## 解决方案
 ## 问题理解

 我们被要求使用“好”或“坏”钥匙打开一系列箱子，每个箱子都包含一定数量的硬币。 一把好的钥匙需要花费固定数量的硬币才能使用，而一把坏的钥匙是免费的，但每个未打开的箱子中的硬币都会减半，包括它打开的箱子，向下舍入。 我们希望在按顺序打开所有宝箱后最大化我们拥有的硬币总数。 

输入给出了箱子的数量、一把好钥匙的成本以及每个箱子中的硬币数量。 输出是可实现的最大硬币。 从概念上讲，我们正在决定，对于每个箱子，是立即花费硬币以获得全部价值，还是采取自由行动来减少未来的收益。 

限制很重要：每个测试用例最多 100,000 个箱子，最多 10,000 个测试用例。 总和为`n`所有测试用例的数量限制为 100,000，这意味着每个测试用例复杂度为 O(n) 的任何解决方案都是可行的。 对好/坏密钥选择的所有序列进行强力探索是指数级的且不可行，因为即使是 20 个箱子也需要检查超过一百万个序列。 硬币和密钥成本的值可以达到 10^9，因此整数溢出是具有 32 位整数的语言的一个问题。 

非明显的边缘情况包括零硬币的箱子、好钥匙的成本为零的情况以及所有硬币相等的情况。 例如，如果`n = 2`,`k = 1`， 和`a = [0, 10]`，在第一个箱子上使用一把好钥匙是浪费，因为它没有硬币。 在第一个箱子上使用坏钥匙会使第二个箱子减半，因此最好跳过或仔细调整选择。 

## 方法

 最直接的方法是暴力破解：对于每个箱子，考虑两种密钥选择，递归计算生成的硬币，然后选择最大值。 这是可行的，因为它正确地模拟了所有可能的序列，但它失败了，因为每个箱子都会使状态数量加倍。 和`n`最多 10^5，这将需要 O(2^n) 次操作，显然不切实际。 

关键的见解是坏钥匙会将所有剩余的箱子减半，因此连续坏钥匙的效果会呈几何衰减。 这使我们能够扭转问题：我们可以修复最后使用的坏钥匙的数量，然后贪婪地将好钥匙应用于较大的箱子，而不是模拟每个组合。 最佳策略是决定我们将用坏钥匙打开最后多少个箱子。 我们可以迭代坏键的数量`b`从 0 到`n`并计算得到的硬币：最后一个之前的所有箱子`b`拿到好钥匙，最后`b`受到连续减半的影响。 

这是有效的，因为只有当它能够补偿未来减半所损失的代币时，尽早使用一个好的密钥才有价值。 总迭代次数为`n`每个测试用例，如果我们预先计算 2 的幂，则每次计算都可以在 O(n) 或 O(b) 内完成，这在给定约束的情况下足够快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最佳 | O(n^2) 天真，O(n) 带前缀和/幂 | O(n) | 已接受 |

 ## 算法演练

 1.从末尾计算硬币的前缀和，快速知道最后的总和`b`胸部。 这使我们能够有效地计算减半值。 
2. 使用整数除法预先计算 1/2 的幂 (`// 2`）最多 60 次迭代，因为超过该值的减半对于所有值高达 10^9 的箱子都为零。 
3. 迭代`b`从 0 到`n`，代表最后使用的坏密钥的数量。 对于每个`b`，计算通过应用收集的硬币`b`坏键依次位于最后一个`b`胸部。 该公式是`floor(a[i] / 2^j)`以获得适当的权力`j`。 
4. 剩余的`n - b`箱子使用好的钥匙。 减去总成本`(n - b) * k`从这些箱子中收集的硬币总数。 
5. 跟踪所有值的最大值`b`。 最大值是测试用例的答案。 

为什么它有效：该算法保持了对于每个`b`，所有序列都精确地`b`考虑最后的坏键，这保证了我们探索坏键的所有最佳位置。 由于坏钥匙只影响剩余的箱子，任何较早应用坏钥匙的序列都可以表示为一些`b`在本次迭代中。 好的钥匙会贪婪地应用于最大的未受影响的箱子，这确保了不会获得更高的总数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        res = 0
        total_good = 0
        # Start with all coins as if all bad keys were used
        suffix = [0] * (n + 1)
        for i in range(n - 1, -1, -1):
            suffix[i] = suffix[i + 1] + a[i]
        max_coins = 0
        pow2 = 1
        for b in range(n + 1):
            coins_from_bad = 0
            for i in range(n - b, n):
                coins_from_bad += a[i] // pow2
            coins_from_good = suffix[0] - suffix[n - b] - (n - b) * k
            max_coins = max(max_coins, coins_from_good + coins_from_bad)
            pow2 *= 2
        print(max_coins)

solve()
```该代码首先计算后缀总和，以快速评估好密钥部分的硬币总数。 它迭代最后使用的坏键的数量，使用重复的整数除法来计算它们的影响，以模拟连续的减半。 乘法`pow2`每一步加两，确保每次减半都得到正确计算。 

微妙之处包括仔细处理整数除法，以便自动向下舍入，避免浮点错误。 使用`suffix`允许 O(1) 访问坏钥匙之前的箱子总和，从而无需在循环内重复求和。
