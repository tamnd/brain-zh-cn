 ## 解决方案
 ## 问题理解

 给定一个短小写字符串的集合，每个字符串的长度最多为 8。对于列表中的每个字符串，我们需要确定是否可以通过从同一列表中取出两个字符串并按顺序连接它们来形成它。 两个选择的字符串允许是相同的元素，并且我们不需要使用不同的索引。 

所以对于每个字符串$s_i$，我们本质上是在问是否存在一个分割点，使得前缀是集合中的某个字符串，后缀也是集合中的某个字符串。 

约束结构在这里非常重要。 即使所有测试用例的字符串总数达到$10^5$，每个单独的字符串都非常短，最大长度为 8。这立即表明任何严重依赖于字符串长度的方法（例如枚举所有子字符串或所有拆分）都是安全的，因为每个字符串最多有 7 个拆分位置。 

然而，为每个查询尝试所有字符串对的简单方法仍然太慢。 如果我们尝试检查每一个$s_i$针对所有对$(s_j, s_k)$， 那是$O(n^3)$最坏情况下的字符串连接检查，这对于$10^5$。 

在考虑订购时会出现一个更微妙的问题。 由于字符串可以由两个较小的字符串组成，因此这些较小的字符串可能出现在输入顺序中的任何位置，不一定出现在当前字符串之前。 这排除了任何贪婪或仅前缀的构造，除非我们明确考虑整个集合。 

通常破坏不正确解决方案的边缘情况来自重复和自连接。 

一个例子是这样的情况：

 输入：```
1
3
a
aa
aaa
```正确的输出是：```
011
```因为“aa”=“a”+“a”并且“aaa”=“aa”+“a”。 

如果一种有缺陷的方法假设至少有一个部分必须按输入顺序出现在前面，或者不允许使用同一字符串两次，则该方法可能会失败。 

另一种微妙的情况是存在多个分解，但只需要一个有效。 例如，“abc”可以拆分为“a”+“bc”或“ab”+“c”。 我们只需要存在一个有效的分割。 

## 方法

 蛮力的想法很简单：对于每个字符串$s_i$，尝试每一个可能的分割位置。 对于每个分割位置，检查给定字符串集中是否存在前缀和后缀。 由于每个字符串的长度最多为 8，因此每个字符串最多有 7 个分割，并且每个成员资格检查可以使用哈希集在恒定时间内完成。 

这已经将问题减少到大约$O(n \cdot L)$， 在哪里$L \le 8$，大致如此$O(n)$。 然而，我们需要小心如何有效地验证成员资格以及如何避免意外重用部分构造的状态。 

不同但等效的观点使结构更加清晰。 我们首先将所有字符串插入到哈希集中，而不是考虑每个字符串。 然后，对于每个字符串，我们测试所有分割点并检查这两个部分是否都存在于集合中。 这是可行的，因为该问题不需要两个部分是不同的字符串或以任何特定顺序出现不同的情况。 

关键的见解是较小的最大长度完全消除了复杂预处理的需要。 整个难度降低为检查每个字符串的所有可能分区并测试集成员资格。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（字符串对）|$O(n^2 \cdot L)$|$O(n)$| 太慢了|
 | 分割+哈希集 |$O(n \cdot L)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 将所有输入字符串存储在哈希集中，以便任何子字符串的成员资格查询平均时间为恒定时间。 这个全局结构代表了我们可以使用的所有可能的构建块。 
2. 对于每个字符串$s$，迭代所有可能的分割位置$i$从 1 到$|s|-1$。 每个分裂都划分$s$变成前缀$s[0:i]$和后缀$s[i:]$。 我们检查所有分区的原因是任何有效的构造都必须恰好对应于这些分区之一。 
3. 对于每个分片，检查前缀和后缀是否都存在于哈希集中。 如果两者都存在，我们可以立即得出结论：$s$是可构造的并将其标记为有效。 
4. 如果没有分割产生两个有效的字典字符串，则将该字符串标记为无效。 
5. 对每个测试用例独立重复此操作，重建每个用例的哈希集。 

为什么它有效：每个有效的表示$s = a + b$唯一对应于分割索引$s$。 由于我们枚举了所有可能的拆分索引，因此我们涵盖了所有可能的分解。 哈希集保证我们正确检测每个候选片段是否存在于输入中的任何位置，而与顺序或多重性约束无关。 由于重复项存储在集合表示形式（或等效的频率感知结构，如果需要）中，因此自然允许自用。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = [input().strip() for _ in range(n)]
        st = set(arr)

        res = []
        for s in arr:
            ok = False
            m = len(s)
            for i in range(1, m):
                if s[:i] in st and s[i:] in st:
                    ok = True
                    break
            res.append('1' if ok else '0')

        print(''.join(res))

if __name__ == "__main__":
    solve()
```该解决方案构建一组用于常量时间成员资格检查，然后独立评估每个字符串。 内部循环尝试除琐碎的空分割之外的每个分割点。 一旦找到有效的分解，它就会短路，因为存在才是最重要的。 

切片操作是安全的，因为字符串长度最多为8，因此实际中每个子串的提取都是常数时间。 

一个常见的实现错误是忘记重建每个测试用例的集合，这将导致先前测试用例的字符串错误地影响结果。 另一个微妙之处是允许重复使用同一字符串； 这是自然处理的，因为该集合不跟踪每个查询的使用计数。

 ## 边缘情况

 对于像字符串“aa”这样的自连接情况，算法会检查位置 1 处的拆分。前缀“a”和后缀“a”都在集合中找到，因此该字符串被正确标记为有效。 

对于缺少一个部分的情况，例如“ab”中仅存在“a”但不存在“b”，每个拆分至少会失败一次成员资格检查，因此该字符串被正确标记为无效。 

对于像“aaa”与“a”和“aa”这样的链式结构，使用前缀“aa”和后缀“a”在位置2处的分割成功，表明该算法正确支持多步骤组合，而不需要迭代构建或DP。
