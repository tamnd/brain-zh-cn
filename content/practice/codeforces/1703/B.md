 ## 解决方案
 ## 问题理解

 竞赛系统按时间顺序处理一系列问题解决方案。 输入字符串中的每个字符代表从 A 到 Z 的问题标签，每次出现都意味着某个团队当时解决了该问题。 每次解决问题时，解决团队都会收到一个气球。 此外，如果这是整个序列中第一次解决该特定问题，则该团队将获得一个额外的气球。 

因此，任务是计算字符串的运行总计：每个字符至少贡献一个气球，并在该字母第一次出现时贡献一个额外的气球。 

约束足够小，即使对字符串进行直接模拟也是微不足道的。 测试用例最多 100 个，字符串长度最多 50 个，总操作次数最多几千次。 任何跟踪每个角色状态的解决方案都足够快。 

主要的微妙之处在于理解“首次解决”是整个序列的全局性，而不是每个团队或每个位置。 一旦出现问题字母，以后出现的所有字母都应该只给出一个气球。 

一个常见的错误是尝试通过每次扫描前缀来重新计算解决方案是否是“第一个”。 例如，对于输入`BAAAA`，如果我们错误地从头开始重新计算每个字符，我们可能会意外地错误计算或使逻辑不必要地复杂化。 另一个错误是忘记了重复的字母每次仍然会给出一个气球。 

## 方法

 暴力解释是处理字符串中的每个位置，并且对于每个字符，扫描所有先前的位置以检查它之前是否出现过。 如果它从未出现过，我们将在答案中添加 2，否则添加 1。 

这是有效的，因为“第一次出现”的定义纯粹是基于前缀的。 然而，检查每个字符的整个前缀使得每个步骤的复杂度为 O(n)，从而导致每个测试用例的复杂度为 O(n²)。 当 n 达到 50 时，这仍然没问题，但对于如此小的约束问题来说，它是不必要的复杂性。 

简化一切的观察是我们只需要记住我们之前是否见过每个问题字母。 长度为 26 的固定大小布尔数组就足够了。 一旦看到一个字母，我们就会对其进行标记，并且所有未来出现的字母都会自动被认为是非第一个。 

这将整个问题简化为每个测试用例一次线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 已接受但矫枉过正|
 | 最优（集合/数组）| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们维护一个记录哪些问题字母已经出现的结构。 

1、初始化一个大小为26的布尔数组，设置为false，代表还没有解决任何问题。 还将气球总数计数器初始化为零。 
2. 按顺序遍历字符串中的每个字符。 每个字符对应一个特定的问题。 
3. 对于每个字符，在使用布尔数组之前检查它是否已经见过。 如果还没有看到，这是该问题的第一个解决方案，因此我们在答案中添加 2 并将其标记为已看到。 
4. 如果已经看到，我们只在答案中添加 1，因为它不再是第一个解决方案。 
5.处理完所有字符后，输出累加总数。 

关键思想是布尔数组将所有必要的历史信息编码在恒定的空间中，因此每个决策都可以在恒定的时间内做出。 

### 为什么它有效

 在扫描中的任何一点，布尔数组都准确地表示在以当前索引结尾的前缀中至少出现过一次的问题集。 这确保了当我们处理一个字符时，“第一次看到”的检查根据定义是正确的：当且仅当它尚未被标记时它才是第一个。 由于标记在第一次遇到后立即发生并且永远不会重置，因此不变量在整个扫描过程中保持不变，使每个决策都与问题规则一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        seen = [False] * 26
        total = 0

        for ch in s:
            idx = ord(ch) - ord('A')
            if not seen[idx]:
                total += 2
                seen[idx] = True
            else:
                total += 1

        print(total)

if __name__ == "__main__":
    solve()
```该解决方案循环遍历每个测试用例并维护一个固定大小的数组`seen`对于字母表。 映射`ord(ch) - ord('A')`将字符转换为从 0 到 25 的索引。条件分支直接编码评分规则：未见过的字符贡献 2，见过的字符贡献 1。 标记的顺序在概念上很重要，但处理得正确，因为我们仅在识别出第一次出现后才进行标记。

 ## 边缘情况

 关键的边缘情况是字符串由单个重复字符组成。 用于输入`AAAAA`，算法标记`A`在第一步中未见，然后将所有后续事件视为已见。 迹线显示第一步贡献 2，其余四步各贡献 1，产生 6。 

另一种情况是所有字符都不同，例如`ABCD`。 每个字符在第一次遇到时都是看不见的，因此每一步都会加 2。算法会立即标记每个字母，确保以后不会混淆，最终结果变为 8。 

混合交替模式，例如`ABACBC`确认一旦一个字母被标记，它就永远不会恢复“看不见”的状态，这保证了即使字符在长时间间隔后重新出现时的一致性。
