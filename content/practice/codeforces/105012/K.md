 ## 解决方案
 ## 问题理解

 我们正在模拟一群人在无限整数网格上移动。 每个人都会在给定的时间出现，从固定的坐标开始，并且最初面向北方。 时间以离散的分钟为单位前进，每个活跃的人每分钟都会按照固定的顺序执行两个动作。 

首先，每个人都会观察位于与他们当前面向的方向垂直且经过其位置的线上的所有人员。 如果它们朝北或朝南，则这条线是其 y 坐标处的整个水平行。 如果它们朝东或朝西，则这条线是其 x 坐标处的垂直柱。 他们统计了该线路上的所有人，包括他们自己和共享牢房的其他人。 如果计数为奇数，则它们顺时针旋转 90 度。 

其次，在所有的轮换都确定之后，每个人都朝着当前的方向精确地前进一步。 

新人在特定分钟开始时加入，始终在其初始坐标处面向北。 在这个过程的 m 分钟之后，我们必须报告在 m 分钟开始时、在那分钟的任何行动之前所有人的位置。 

约束足够小，使得随着时间的推移进行直接模拟是可行的，但也不会小到我们可以在每个步骤中进行低效的重新计算。 当 n 和 m 达到 1000 时，模拟的人分钟总数最多约为 100 万，这排除了任何试图在每人每步的线性时间内重新计算全局信息的方法，因为这将导致大约 10^9 次操作。 

微妙的困难在于，“在线计数”取决于当前活跃的所有人员，并且这些位置每分钟都在变化。 通过扫描所有人中的每个人来重新计算这些计数的简单实现会太慢。 

一个常见的陷阱是忘记更新是同时发生的。 如果我们一个接一个地移动人员并立即更新计数，则同一分钟内稍后的人员将看到部分更新的状态，这是不正确的。 到达时出现另一个问题：在时间 t 进入的人必须从该分钟的决策阶段开始参与，而不是在移动已经发生之后。 

## 方法

 暴力模拟将在每一分钟迭代每个人，并扫描所有其他活跃的人，根据他们的方向计算有多少人躺在同一行或同一列上。 这使得每分钟的成本为 O(k^2)，其中 k 是活跃人数。 在 m 分钟内，这会退化为 O(n^2 m)，在最坏的情况下达到大约 10^9 次操作，并且速度太慢。 

关键的观察是我们不需要从头开始重新计算这些计数。 每个人需要的唯一信息是当前有多少人共享他们的行或列。 这些计数可以使用散列映射来增量维护：一个将 y 坐标映射到该行中的人数，另一个将 x 坐标映射到该列中的人数。 

通过这些结构，每个人都可以在 O(1) 时间内确定其相关行上的计数是否为奇数。 剩下的唯一挑战是在人们移动时保持这些计数正确。 由于所有移动在做出决策后同时发生，因此我们首先使用当前计数快照计算所有方向变化，然后应用所有移动并相应地更新地图。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2 m) | O(n^2 m) | O(n) | 太慢了|
 | 使用哈希图进行增量计数 | O(n·m) | O(n) | 已接受 |

 ## 算法演练

 我们一分钟一分钟地模拟时间，维持所有活跃人群的当前状态。

1. 我们为每个人存储他们当前的位置、方向以及他们是否活跃。 当当前时间到达他们的到达时间时，一个人就会变得活跃。 
2. 在每分钟开始时，我们将所有新到达的人插入活动集中。 它们的方向初始化为北，并且它们立即贡献于行和列计数。 
3. 我们维护两个频率图：一个计算每个 y 坐标当前有多少人，另一个计算每个 x 坐标有多少人。 
4. 对于每个活跃的人，我们决定他们是否轮换。 如果它们朝北或朝南，我们会在其 y 坐标处查询行地图。 如果它们朝东或朝西，我们会在其 x 坐标处查询列图。 如果该值为奇数，我们顺时针旋转 90 度。 

这样做的原因是规则仅取决于一分钟开始时的状态，因此我们在决定方向时不能修改地图。 

1. 所有方向确定后，我们从地图中删除每个人的旧位置，将他们向其方向移动一个单位，然后将新位置插入回地图中。 
2. m分钟后，我们输出所有最终坐标。 

正确性取决于在每分钟开始时保持系统快照的一致性。 每个决策仅使用该快照，然后应用所有更新。 这可以确保没有人在同一分钟内影响另一个人的决定。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    x = []
    y = []
    t = []
    for _ in range(n):
        xi, yi, ti = map(int, input().split())
        x.append(xi)
        y.append(yi)
        t.append(ti)

    # directions: 0=N,1=E,2=S,3=W
    dx = [0, 1, 0, -1]
    dy = [1, 0, -1, 0]

    dirc = [0] * n
    active = [False] * n

    row_cnt = {}
    col_cnt = {}

    def add(i):
        row_cnt[y[i]] = row_cnt.get(y[i], 0) + 1
        col_cnt[x[i]] = col_cnt.get(x[i], 0) + 1

    def remove(i):
        row_cnt[y[i]] -= 1
        if row_cnt[y[i]] == 0:
            del row_cnt[y[i]]
        col_cnt[x[i]] -= 1
        if col_cnt[x[i]] == 0:
            del col_cnt[x[i]]

    ptr = 0

    for _ in range(m):
        while ptr < n and t[ptr] == _:
            active[ptr] = True
            add(ptr)
            ptr += 1

        # decide directions using snapshot
        for i in range(n):
            if not active[i]:
                continue
            if dirc[i] % 2 == 0:
                cnt = row_cnt[y[i]]
            else:
                cnt = col_cnt[x[i]]
            if cnt % 2 == 1:
                dirc[i] = (dirc[i] + 1) % 4

        # move all
        for i in range(n):
            if not active[i]:
                continue
            remove(i)
            x[i] += dx[dirc[i]]
            y[i] += dy[dirc[i]]
            add(i)

    for i in range(n):
        print(x[i], y[i])

if __name__ == "__main__":
    main()
```该实现使模拟每分钟严格同步。 这`row_cnt`和`col_cnt`地图表示移动之前的状态，并且仅在计算所有方向变化后才更新它们。 

一个微妙的细节是决策阶段和行动阶段之间的分离。 如果我们在改变方向时立即更新位置，则同一分钟内的后续计算将看到不一致的计数。 另一个重要的细节是使用排序后的指针来处理到达`t`数组，确保每个人在正确的时间被激活一次。 

## 工作示例

 考虑第一个示例，其中三个人在不同时间进入。 最初只有第一个人存在，因此他们的移动不受干扰。 当第二个人出现时，两者都会对行数和列数产生影响，这可能会改变随后几分钟内的转弯行为。 

| 分钟 | 活动集| 关键计数 | 方向改变| 搬迁后的职位|
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 行=1，列=1 | 没有转弯| (1,2) → (1,3) |
 | 1 | 1,2 | 共享行/列已更新 | 双方都有可能轮到| 更新职位 |
 | 2 | 1,2,3 | 全程互动| 奇偶校验影响轮数| 最终坐标演变|

 第二个示例强调多人共享坐标的重复交互，导致频繁的奇偶翻转，从而影响旋转行为。 

这些痕迹证实系统仅取决于当前行和列占用的奇偶性，而不取决于几何距离或排序。

 ## 边缘情况

 一个关键的边缘情况是多人占用同一个牢房。 在这种情况下，行和列计数包含重复项，这直接影响奇偶校验。 该算法自然地处理了这个问题，因为计数是按人而不是按位置维护的。 

另一种情况是到达恰好在一分钟边界处。 由于激活发生在该分钟的决策阶段之前，因此新到达的人会立即对计数做出贡献，并可能影响同一步骤中的轮次。 基于指针的插入确保了这种排序。 

最后一个微妙的情况是同时交叉路径，即两个人在一次移动中交换位置。 由于所有更新都是在计算方向后应用的，因此两种移动都基于相同的初始快照，从而防止任何排序伪影。
