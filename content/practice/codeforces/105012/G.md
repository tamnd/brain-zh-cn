 ## 解决方案
 ## 问题理解

 我们给出了一个完整的无向图，顶点标记为 1 到 n。 每对不同的顶点 i 和 j 都相连，并且该边的权重定义为 gcd(i, j)。 从这个稠密图中，我们必须恰好选择 n − 1 条边来形成生成树，并且所选边权重的总和必须恰好为 k。 如果不存在这样的树，我们必须报告不可能性。 

关键的困难不是连通性，因为任何生成树总是存在于完整的图中。 真正的约束是控制 gcd 权重的总和，同时仍然保持树结构。 由于每个边权重都是由顶点标签确定的，因此我们可以有效地在具有非常特殊的算术权重函数的固定加权完整图上选择结构。 

约束很大：n 最多可达 10^6，并且最多有 5 × 10^5 个测试用例，测试用例总数 n 以 10^6 为界。 这会立即排除每次测试中 n 的任何二次方。 即使每个测试的 O(n log n) 也必须小心处理，并且任何解决方案在所有测试中都必须本质上是线性的。 

当 n 很小时，会出现微妙的边缘情况。 对于 n = 2，只有一条边，因此答案是固定的。 如果 k 与 gcd(1, 2) = 1 不同，则不可能。 当 k 非常大（高达 10^12）时，会出现另一个棘手的情况，而由于 gcd 值的结构，最大可能的树权值要小得多，这会强制出现早期拒绝条件。 

主要的隐藏困难是，尽管所有对之间都存在边，但任何最佳构造中最有用的边的权重都是 1，只有精心选择的边才会贡献更高的权重。 

## 方法

 暴力方法会尝试所有生成树并计算它们的总 gcd 和。 即使忽略树数量的组合爆炸，仅生成完整图的生成树也是指数级的。 根据凯莱公式，有 n^(n−2) 个生成树，并且评估每个生成树是不可能的。 

一种更结构化的暴力方法是考虑贪婪地构建一棵树，总是尝试边缘和回溯来匹配 k 和。 这仍然失败，因为每一步都取决于全局结构，并且分支因子仍然巨大。 

关键的结构见解是停止考虑任意生成树，而是构建具有固定主干的有根树，然后仔细控制仅增加总和的少量边。 由于所有边的 gcd(i, j) 至少为 1，如果所有边都选择权重 1，则基线生成树自然会贡献权重 n − 1。高于 n − 1 的任何附加贡献必须来自 gcd(i, j) ≥ 2 的边。 

这表明我们应该从所有边的权重均为 1 的树开始，然后有选择地用更高 gcd 的边替换一些边，以受控增量增加总和。 唯一可以贡献更大 gcd 值的顶点是那些共享除数的顶点，因此按两个或其他结构化倍数的幂对顶点进行分组变得至关重要。 标准结构使用以 1 为根的星形主干，因为所有 x 的 gcd(1, x) = 1，从而给出了干净的基线。 

从那里开始，可以以某种方式附加一些 i 的倍数的顶点，从而在需要时产生更高的 gcd 贡献，从而通过重新路由父链接有效地允许控制权重增量。

 ## 算法演练

 我们构建一个基础生成树，然后调整它以达到所需的总权重 k。 

### 第 1 步：构建基线树

 我们首先将每个顶点 i（i ≥ 2）连接到顶点 1。这立即形成一个有效的生成树。

该树的总权重为 n − 1，因为每条边 (1, i) 的权重 gcd(1, i) = 1。这给出了保证的最小可实现总权重。 

### 第 2 步：检查可行性

 如果 k < n − 1，我们会立即失败，因为每个生成树必须至少有 n − 1 条边，并且每条边的权重至少为 1。因此，最小可能总数为 n − 1。 

### 第三步：了解如何增加体重

 为了将总权重增加到 n − 1 以上，我们必须用边 (i, j) 替换一些边 (1, i)，其中 gcd(i, j) > 1。这种替换的增益是 gcd(i, j) − 1。 

我们希望累积总增益等于 k − (n − 1)。 

### 步骤 4：使用可分结构

 我们以从 n 到 2 的降序处理顶点。对于每个顶点 i，我们尝试将其不连接到 1，而是连接到树中已有的 i 的某个倍数 j。 如果我们将 i 连接到 j，其中 j 是 i 的倍数，则 gcd(i, j) = i，与基线相比产生 i − 1 的增益。 

这允许总重量的大幅受控跳跃。 

### 步骤 5：贪婪分配收益

 我们维持剩余所需增益 R = k − (n − 1)。 对于从大到小的每个 i，如果我们可以使用 i 作为增益源（意味着我们仍然有可用的 i 倍数的顶点），我们将 i 附加到一个这样的倍数并将 R 减少 i − 1。 

我们通过始终连接到先前包含的节点来确保不会中断连接。 

### 步骤 6：最终确定剩余节点

 任何不用于增益调整的节点都附加到 1，保留权重 1 边。 

### 为什么它有效

 该构造依赖于以下不变量：当前图始终是一棵以 1 为根的有效树，并且每次修改都恰好替换一条边，同时保留连通性。 每次成功的“升级”都会用权重 i 的边替换权重 1 的边，从而使总权重恰好增加 i − 1。由于每个增益步骤都是独立的并使用不相交的边，因此可以精确控制总和，而不会干扰之前的选择。 

可整除性保证确保每当我们将 i 连接到 i 的倍数时，gcd 正是 i，这使得增量精确且可预测。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        
        if k < n - 1:
            print(-1)
            continue
        
        # initial tree: star at 1
        parent = [0] * (n + 1)
        used = [False] * (n + 1)
        parent[1] = 0
        
        # baseline connections
        for i in range(2, n + 1):
            parent[i] = 1
        
        remaining = k - (n - 1)
        
        # try to upgrade edges
        for i in range(n, 1, -1):
            if remaining <= 0:
                break
            
            # try to attach i to a multiple of i
            # we search for any j = 2*i, 3*i, ...
            if not used[i]:
                for j in range(2 * i, n + 1, i):
                    if parent[j] == 1 and remaining >= i - 1:
                        parent[j] = i
                        used[i] = True
                        remaining -= (i - 1)
                        break
        
        if remaining != 0:
            print(-1)
        else:
            for i in range(2, n + 1):
                print(i, parent[i])

if __name__ == "__main__":
    solve()
```该实现首先构建以 1 为根的最小星形树。这保证了生成树有效，并给出了可预测的基线成本 n − 1。变量`remaining`跟踪需要多少额外重量。 

贪婪循环尝试通过将 i 的某个倍数直接连接到 i 而不是 1 来使用每个 i 作为“权重源”。这是唯一增加总权重的操作，因为将 Parent[j] 从 1 替换为 i 会将边权重从 1 增加到 i。 

这`used`array 确保我们不会多次重复使用相同的 i，从而保持构造的一致性。 内循环扫描 i 的倍数并执行第一个可行的升级，使剩余预算保持非负数。 

最后，如果剩余所需增益不完全为零，我们输出 -1，因为部分完成将违反精确的目标总和约束。

 n = 5，k = 5

我们首先考虑 i = 2。 2的倍数是4。 

| 步骤| 行动| 家长变更 | 剩余收益|
 | --- | --- | --- | --- |

 输出树边：

 (1,2), (1,3), (2,4), (1,5)

 总重量变为 1 + 1 + 2 + 1 = 5。 

这显示了单个 gcd 升级如何精确匹配所需的增量。

这证实了下界 n − 1 很紧，有时向上无法到达。

 ## 边缘情况

 当 n = 2 时，图仅包含一条边。 该算法通过将 k 与 n − 1 进行比较来立即检查可行性。由于 n − 1 = 1，因此只有 k = 1 有效。 该构造输出单边 (1, 2)，并且不会发生进一步的处理，因此不会进行无效的调整尝试。 

当 k < n − 1 时，算法会在构建任何结构之前提前拒绝。 例如，n = 10、k = 5 会立即触发失败，因为任何生成树的总权重必须至少为 9。 

当k非常大时，贪婪升级过程最终会耗尽所有可能的gcd增益。 如果剩余最后不为零，则算法输出 -1，正确捕获并非所有大目标都可以由基于 gcd 的增量表示。
