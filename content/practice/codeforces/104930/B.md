 ## 问题理解

 我们得到一个写成一串数字的门牌号。 该城市有一个对称规则：当您将数字旋转 180 度时，它仍然必须使用相同的数字系统形成有效的可读数字。 

只有一组有限的数字能够在旋转后幸存下来：0、1、6、8 和 9。一些数字在旋转后保持不变（0、1、8），而其他数字则相互转换（6 变成 9，9 变成 6）。 该组之外的任何数字都会立即违反规则，因为它在旋转后变得不可读。 

有效的门牌号必须同时满足两个条件。 首先，颠倒读取必须在旋转映射下产生一致的数字串。 其次，原始数字和旋转后的版本都不允许以 0 开头，因为任一方向都不可接受前导零。 

输入是表示为字符串的单个整数，并且其表示形式中可能包含前导零。 任务是确定该号码是否可以作为这些规则下的有效 Upside Downtown 门牌号存在。 

约束足够小，对数字进行线性扫描就足够了。 数字的长度最多为 10，因此任何 O(n) 甚至 O(n^2) 方法都非常快。 这将焦点完全转移到数字映射规则的正确性和仔细处理上，而不是性能上。 

主要的边缘情况来自边界数字和无效旋转。 像 680 这样的数字在视觉上看起来很合理，但旋转后它变成了 089，它从零开始，违反了规则。 同样，像 0 这样的单个数字也很棘手，因为它在旋转下有效，但由于前导零限制而无效。 另一个微妙的情况是确保两端的数字配对一致，因为任何镜像对中的不匹配都会破坏整个结构。 

## 方法

 一种直接的方法是显式模拟旋转。 我们获取该数字，通过反转字符串并应用数字映射来构建其旋转版本，然后检查原始字符串和旋转字符串是否都是有效数字。 这是有效的，因为旋转的表示完全捕获了数字在 180 度旋转后的显示方式。 正确性是立竿见影的，因为我们直接构建我们想要验证的内容。 

这种强力方法会扫描字符串一次以构建旋转版本，然后执行一些检查。 即使我们做了额外的冗余工作，输入大小也很小，性能也不是问题。 但是，如果忘记验证无效数字或错误处理旋转结果中的前导零，粗心的实现仍然可能会失败。 

关键的观察是我们不需要构建任何超出成对验证的东西。 每个数字必须与对称位置处的旋转对应数字相匹配。 这减少了检查具有固定映射的镜像对的问题，同时在两端分别实施前导数字约束。 

暴力破解之所以有效，是因为它显式地构造了转换后的字符串，但它做了不必要的额外工作。 旋转是局部成对映射的观察结果使我们能够在一次传递中验证结构，而无需构建中间字符串。

 ## 算法演练

 我们通过检查旋转映射下的对称性来验证该数字。 

### 1. 将数字读取为字符串

 我们将其保留为字符串，以便我们可以访问各个数字而不会出现数字转换问题。 

### 2.如有数字无效，立即拒绝

 我们确保每个字符都是 0、1、6、8 或 9 之一。任何其他数字都无法在旋转中幸存。

### 3.定义旋转映射

 我们使用固定映射0→0、1→1、8→8、6→9、9→6。 这定义了每个数字在 180 度旋转下如何变换。 

### 4.检查镜像一致性

 对于从一开始的每个位置 i，我们将 s[i] 与 s[n−1−i] 的映射版本进行比较。 如果任何对不一致，则该数字在轮换后就不能保持有效。 

### 5. 强制前导数字限制

 我们确保 s[0] 不是“0”，因为原始数字不能从零开始。 我们还确保旋转后的数字不从零开始，这意味着 s[n−1] 不能为“0”。 

### 6. 仅当所有检查都通过时才确认有效性

 如果所有镜像对都匹配并且两个边界约束都成立，则该数字有效。 

### 为什么它有效

 每个数字位置都与旋转时的一个相反位置配对。 该映射在允许的数字集上是双射的，因此所有镜像对的一致性保证了整个旋转字符串的定义明确且有效。 边界检查强制执行外部约束，即两个方向都不能从零开始，这并不是仅由成对对称性强制执行的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    allowed = set("01689")
    mp = {
        "0": "0",
        "1": "1",
        "8": "8",
        "6": "9",
        "9": "6"
    }

    n = len(s)

    if s[0] == "0":
        print("NO")
        return
    if s[-1] == "0":
        print("NO")
        return

    for ch in s:
        if ch not in allowed:
            print("NO")
            return

    for i in range(n):
        if mp[s[i]] != s[n - 1 - i]:
            print("NO")
            return

    print("YES")

if __name__ == "__main__":
    solve()
```实现直接遵循算法。 第一个检查尽早删除无效的边界情况，尤其是在任一方向都会产生前导零的数字。 允许的集合确保没有非法数字参与转换。 

镜像循环是核心逻辑。 应用旋转映射后，将每个索引与其对称对应项进行比较。 这避免了显式构造旋转字符串并确保恒定的额外空间使用。 

一个常见的错误是忘记旋转的前导数字对应于原始的最后一位数字。 这就是为什么在验证之前或期间必须独立检查两端的原因。 

## 工作示例

 ### 示例 1：`801`我们讨论对称性和映射。 

| 我| s[i] | s[n-1-i] | s[n-1-i] 映射 s[i] | 检查|
 | ---| ---| ---| ---| ---|
 | 0 | 8 | 1 | 8 | 8 == 1 已经失败 |

 第一次比较失败，因为 8 映射到 8，但相反的数字是 1，破坏了对称性。 然而，这实际上是一个微妙的情况：正确的验证应该尽早检测到不匹配，但还要注意，只有在完全一致性成立的情况下，旋转形式才有效。 在此示例中，预期的解释是，只要结构一致，对称性就可以在完全旋转规则下发挥作用； 这里的不匹配立即表明无效。 

该轨迹显示了算法在不进一步扫描的情况下拒绝不一致配对的速度。 

### 示例 2：`680`| 我| s[i] | s[n-1-i] | s[n-1-i] 映射 s[i] | 检查|
 | ---| ---| ---| ---| ---|
 | 0 | 6 | 0 | 9 | 9 == 0 | 9 == 0

 第一个不匹配已经破坏了有效性。 即使允许所有数字，旋转下的结构不匹配也会使数字无效。 

这表明仅拥有有效数字是不够的，需要结构对称。

 ## 边缘情况

 单个数字输入，例如`0`同时暴露这两个约束。 根据循环规则，它是有效数字，但它违反了数字不能以零开头的规则。 该算法通过前导数字检查立即捕获这一点。 

像这样的输入`69`显示了一个干净有效的转换。 数字 6 映射到 9，9 映射到 6，并且对称性完美成立。 该算法通过匹配镜像位置来确认这一点。 

像这样的案例`680`间接证明了旋转前导零问题。 即使允许所有数字，最后一个数字也会成为旋转形式的第一个数字，并且由于结构限制而导致验证失败。
