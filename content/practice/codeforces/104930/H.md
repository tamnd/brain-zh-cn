 ## 解决方案
 ## 问题理解

 我们被要求计算长度的序列$N$其中每个位置都包含从 13 个面额的固定有序集合中选择的“等级”：A 是最小的，其次是 2，直到 King。 

对序列的限制是不寻常的：当我们从左向右移动时，下一张牌要么与上一张牌相比，其等级必须严格增加，要么无论之前的值如何，它都可能是 Ace。 所以序列大多是递增的，但 A 的行为就像一个特殊的重置符号，可以不受限制地出现在任何地方。 

仅当至少一个位置具有不同的排名时，两个序列才被视为不同，因此这纯粹是排名字符串的计数问题。 

关键限制是本地的：每个位置仅取决于前一张牌。 这立即表明了关于位置和最后看到的排名的动态规划公式。 

自从$N \le 20$，每个位置有 13 或 14 个状态的任何指数都可以。 真正的约束是概念上的，而不是计算上的。 

当序列重复使用 Ace 时，会出现微妙的边缘情况。 例如，对于$N=3$，序列如$A, A, A$即使它们没有在任何地方“增加”，也是有效的。 强制严格增长（偶尔重置除外）的幼稚解释可能会错误地禁止重复的 Ace 或错误处理涉及 Ace 的转换。 

另一个微妙的情况是将 A 视为最小的和通配符。 规则是不对称的：A 总是被允许作为下一个元素，即使是在 K 之后。 如果按照严格的顺序将 Ace 建模为排名 1，则仍然必须允许从 King 到 Ace 的过渡，如果不单独处理，这会破坏标准的递增序列 DP。 

## 方法

 暴力方法将生成所有可能的长度序列$N$超过13个等级，检查每个等级是否满足规则，并统计有效等级。 这给出了$13^N$序列。 为了$N = 20$，这是关于$10^{22}$，即使进行修剪也是完全不可行的。 

约束的结构建议基于最后选择的排名的动态编程状态。 关键的观察结果是，有效性仅取决于前一张牌以及当前牌是否是 A 或严格大于它。 这种局部依赖性意味着我们可以增量地构建序列，而无需记住整个历史记录。 

我们根据位置和最后一个等级定义 DP，其中转换考虑所有允许的下一个等级。 来自排名最后的州$x$，我们可以去任何等级$y > x$，或 Ace，无论$x$。 这在状态上创建了一个有向非循环结构，但 Ace 的行为类似于从每个状态连接的全局重置。 

优化来自于认识到到“任何更高等级”的转换可以使用前缀和进行聚合，而 Ace 转换则贡献来自所有状态的统一加法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(13^N \cdot N)$|$O(N)$| 太慢了|
 | DP 超过等级 |$O(N \cdot 13^2)$|$O(13)$| 已接受 |

 ## 算法演练

 我们将排名视为 0 到 12 之间的整数，其中 0 代表 Ace，12 代表 King。 

1.初始化一个DP数组`dp[r]`表示当前长度以rank结尾的序列数`r`。 对于长度 1，每个等级都同等有效，因此每个状态都以值 1 开始。 
2. 对于每个下一个位置，我们计算一个新的 DP 数组`ndp`。 对于每个可能的当前排名`r`，我们想要计算我们可以通过多少种方式过渡到它。 
3. 晋升职级`r`，我们将所有之前的状态相加`dp[x]`其中任一`x < r`（严格增加条件）或`r`是艾斯。 由于 Ace 总是可以被选择，所以每`dp[x]`为 Ace 状态做出贡献。 
4. 为了有效地计算“所有 x < r 的总和”，我们维护一个前缀总和`dp`。 这使我们能够获得每个状态在恒定时间内严格增加转换的贡献。 
5. 特别是对于 Ace，我们将其单独计算为所有的总和`dp`值，因为从任何先前的排名中我们都可以放置一张 A。 
6.处理完所有等级后，替换`dp`和`ndp`并重复所有位置直到$N$。 
7. 最终答案是所有值的总和`dp`加工后$N$职位。 

### 为什么它有效

 在每一步中，DP 状态仅通过记住最后一个等级来完全总结给定长度的所有有效序列。 转换规则仅取决于最后的等级以及下一张牌是否为 A 或更大。 由于通过前缀转换或全局 Ace 转换，每个有效扩展都被精确计数一次，因此不会遗漏或重复计算任何序列。 前缀和结构确保精确执行“严格递增”约束，而无需重新计算重叠。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input().strip())
    
    # dp[r] = number of sequences ending in rank r
    # 0 = Ace, 1..12 = 2..King
    dp = [1] * 13
    
    for _ in range(n - 1):
        total = sum(dp) % MOD
        
        # prefix sums for strict increases
        pref = [0] * 14
        for i in range(13):
            pref[i + 1] = (pref[i] + dp[i]) % MOD
        
        ndp = [0] * 13
        
        for r in range(13):
            if r == 0:
                # Ace can be placed after anything
                ndp[r] = total
            else:
                # sum of all x < r
                ndp[r] = pref[r] % MOD
        
        dp = ndp
    
    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```该实现遵循上述 DP。 前缀数组`pref`用于快速计算所有先前排名小于当前排名的总和，强制执行严格递增条件。 Ace 状态是使用所有先前状态的总和单独处理的，因为 Ace 忽略排序约束。 

我们精确地迭代$N-1$转换，因为第一个位置是直接初始化的。 

必须小心模运算，尤其是在计算时`total`和前缀和，因为如果不减少，中间和可能会超出整数限制。 

## 工作示例

 ### 示例 1

 输入：```
2
```我们从所有 dp 状态为 1 开始。 

| 步骤| dp（Ace..King）| 总计 | ndp(王牌) | ndp(2..King) | ndp(2..King) |
 | --- | --- | --- | --- | --- |
 | 初始化| 13 个 | - | - | - |
 | 1 步后 | 计算| 13 | 13 | 基于前缀的 |

 对于排名 2（索引 1），我们只能来自 Ace，因此值为 1。对于 Ace，我们可以来自所有 13 个州，给出 13。将有效结局相加得到 91。 

这证实了即使是短序列也已经包含许多 Ace 充当重置的组合。 

### 示例 2

 输入：```
3
```现在DP进一步扩展：

 | 步骤| DP总和|
 | --- | --- |
 | 第一次转换后 | 91 | 91
 | 第二次转换后 | 较大的合计值 |

 第二个转换演示了关键行为：以较高等级结束的序列仅从较小的等级累积，而 Ace 不断注入全状态转换。 

这显示了 Ace 如何通过充当全球连接者来主导组合增长。

 ## 边缘情况

 对于$N = 1$，答案必须正好是 13，因为每个单独的秩作为单元素序列都是有效的。 DP 从全 1 开始，因此最终的和仍然是 13，符合不涉及转换的规则。 

对于 Ace 主导的序列，例如$A, A, A, \dots$，该算法通过 Ace 转换对它们进行计数，该转换始终使用先前状态的总和。 例如，在每一步中，Ace 都会收到来自每个可能的结束状态的贡献，因此重复的 Ace 序列永远不会丢失，并且会作为全局总和的一部分正确累积。 

对于没有 Ace 的严格递增序列，例如$2, 5, 9$，前缀和机制确保每个有效路径只对它们计数一次。 每个扩展仅使用具有较小等级的状态，因此不会引入无效的向后转换。
