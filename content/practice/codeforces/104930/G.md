 ## 解决方案
 ## 问题理解

 我们得到一个小的整数数组，每个测试用例都是独立的。 从该数组中，我们考虑每个可能的元素子集，但不允许我们获取整个数组。 允许空子集，因为它仍然是子集并且不违反“非完整集”条件。 

对于任何选定的子集$S$，我们计算由两部分组成的值：子集的大小及其元素的立方和。 子集大小相乘，符号取决于大小是奇数还是偶数。 具体来说，偶数大小的子集会产生正向贡献，奇数大小的子集会产生负向贡献，并且所有内容都按子集大小本身进行缩放。 

任务是评估每个有效子集的该表达式，并报告每个测试用例的最小值和最大值。 

关键的限制是$N \le 15$。 这是关键信号：尽管子集的数量是$2^N$, 至多$2^{15} = 32768$，因此枚举每个测试用例的所有子集是可行的。 即使有多达 1000 个测试用例，以恒定或非常小的摊余时间处理每个子集的解决方案也是可以接受的。 任何从头开始为每个子集重新计算子集总和的方法都是不可接受的，这会引入一个额外的因子$N$，将复杂性推向 5 亿次操作。 

边缘情况主要与子集选择规则和符号行为有关。 

一个常见的错误是由于“严格子集”的措辞而假设空子集是不允许的。 如果我们排除它，我们将错过值为 0 的有效候选值，当所有其他值严格为正值或负值时，这可能会影响最小值或最大值。 

另一个微妙的情况是完全子集排除。 如果我们不小心将其包含在内，它的贡献可能会占主导地位，因为子集大小乘数和立方和都处于最大值。 

例如，如果$A = [1, 1, 1]$，那么完整的子集将产生$3 \cdot (-1)^3 \cdot 3 = -9$，尽管不应该考虑它，但它可能会错误地成为最小值。 

## 方法

 最直接的方法是使用位掩码迭代每个子集。 对于每个子集，我们计算其大小以及所包含元素的立方和，然后计算表达式。 这是正确的，因为它明确遵循定义。 问题在于重复计算子集和的效率。 

如果我们从头开始重新计算每个子集的立方和，则每个子集最多扫描 15 个元素。 这导致大约$2^N \cdot N$，每个测试用例大约有 500,000 次操作，在所有测试中最坏的情况下高达 5 亿次。 这在 Python 中太慢了。 

这种改进来自于认识到子集形成了自然的 DP 结构。 如果我们将子集表示为位掩码，我们可以增量计算每个子集的立方和。 一个子集可以分解为一个更小的子集加上一个新添加的元素。 这使我们能够计算所有子集总和$O(2^N)$每个测试用例无需重新扫描元素的时间。 

一旦我们有效地获得了子集和，计算每个子集的表达式的时间就是常数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（重新扫描每个子集）|$O(2^N \cdot N)$|$O(1)$| 太慢了 |
 | 子集和上的位掩码 DP |$O(2^N)$|$O(2^N)$| 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 转换各个元素$A_i$转化为它的立方值$A_i^3$。 这避免了重复重新计算能力并保持算术局部于整数。 
2. 使用位掩码 DP 预先计算立方体的子集和。 对于每个掩码，我们隔离其最低有效设置位并将掩码表示为较小的掩码加一个元素。 这保证了每个子集总和在已经计算的结果的基础上计算一次。 
3. 对于每个面具$0$到$2^N - 1$，计算子集大小并计算表达式$|S| \cdot (-1)^{|S|} \cdot \text{sum}(S)$。 
4.跳过全面罩$(1 << N) - 1$，因为该问题禁止使用整个数组。 
5. 跟踪所有有效子集的全局最小值和最大值。 

关键的设计选择是通过 DP 而不是重新计算来计算子集和。 如果没有这个，解决方案将超出时间限制，即使$N$很小。 

### 为什么它有效

 每个子集恰好对应一个位掩码，并且可以通过删除一组位来减少每个位掩码。 DP 确保当我们计算子集时，它所依赖的较小子集是已知的。 这会按位数对掩码进行严格排序，保证不会重新计算，也不会丢失状态。 由于表达式仅取决于子集大小和总和，两者完全由每个掩码确定，因此独立评估每个掩码就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        N = int(input())
        A = list(map(int, input().split()))
        
        nmask = 1 << N
        cube = [x * x * x for x in A]
        
        # subset sum DP over bitmasks
        sub_sum = [0] * nmask
        
        for mask in range(1, nmask):
            lsb = mask & -mask
            idx = (lsb.bit_length() - 1)
            sub_sum[mask] = sub_sum[mask ^ lsb] + cube[idx]
        
        full_mask = nmask - 1
        
        mn = float('inf')
        mx = float('-inf')
        
        for mask in range(nmask):
            if mask == full_mask:
                continue
            
            k = mask.bit_count()
            val = k * sub_sum[mask]
            if k % 2 == 1:
                val = -val
            
            if val < mn:
                mn = val
            if val > mx:
                mx = val
        
        print(mn, mx)

if __name__ == "__main__":
    solve()
```立方体预处理隔离了求幂，以便子集计算变成纯粹的加法。 DP 步骤使用的特性是，删除最低设置位总是会导致已处理的严格较小的掩码。 位索引提取通过`lsb.bit_length() - 1`将隔离位安全地转换为数组索引。 

在评估期间，子集大小通过以下方式获得`bit_count()`，这对于小规模来说是有效的$N$。 乘法后应用符号翻转，以避免运算符优先级错误。

 ## 边缘情况

 空子集是主要的概念边缘情况。 对于像这样的输入$[5]$，唯一允许的子集为空，并且不允许单元素子集，因为它等于完整数组。 该算法仅评估空掩码并正确生成值 0。 

完全子集排除是另一个关键条件。 为了$A = [2, 2]$，包含两个元素的子集将产生$2 \cdot (+1) \cdot (16 + 16) = 64$，但从未考虑过。 循环显式跳过此掩码，确保最大值来自单元素子集。 

当所有元素均为负数时，立方体保留负数，但子集大小的交替符号会产生不直观的翻转。 DP 仍然可以正确处理这个问题，因为它从不假设单调性，它独立于计算的总和来评估每个子集。
