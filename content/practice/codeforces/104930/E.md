 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 在每个测试用例中，一队人按固定顺序站立，每个人要么来自上城区，要么来自下城区。 我们可以选择这条线的一个连续路段，并且我们希望该路段是“平衡的”，这意味着它包含完全相同数量的上城居民和下城居民。 在所有这些平衡段中，我们需要最大可能的长度。 

因此，每个测试用例的关键任务不是找到任何平衡段，而是找到最长的子串，其中`U`和`D`是平等的。 

这些约束足够严格，任何直接检查所有子字符串的方法都是不可行的。 由于测试用例的总长度高达 200,000，每个测试用例的二次扫描在最坏的情况下将导致大约 10^10 次操作，这远远超出了 Python 中 2 秒的限制。 

一些边缘情况在结构上很重要：

 例如，完全由一个字符组成的字符串`UUUUU`，没有正长度的有效段，因此答案必须为 0。假设至少存在一对有效的简单方法将错误地返回至少 2。 

完整的交替字符串，例如`UDUDUD`应该返回完整长度，因为每个前缀都可能在某个时刻得到平衡，但只有在正确跟踪累积平衡之后。 

像这样的案例`UUDDUD`可以有多个不同长度的有效段，并且我们必须确保我们不只是采用第一个平衡前缀。 

## 方法

 蛮力的想法很简单：尝试每一个可能的部分`[l, r]`,数数有多少个`U`和`D`出现，并检查它们是否匹配。 如果他们这样做，请更新答案`r - l + 1`。 这是正确的，因为它明确评估了所有候选人。 

问题是性能。 对于每个起始索引`l`，我们扫描所有`r > l`并重新计算计数，或者即使我们保持运行计数，我们仍然检查每个测试用例的 O(n^2) 段。 总长度达到 2·10^5 时，这会变得太慢。 

关键的观察是我们实际上并不关心原始计数`U`和`D`，但只是它们的区别。 如果我们映射`U`到 +1 和`D`到 -1，则当段的总和为零时，该段恰好达到平衡。 这将问题转化为寻找总和为零的最长子数组。 

这是一个经典的前缀和结构。 如果我们定义`prefix[i]`作为索引的总和`i`，然后是一段`[l, r]`总和为零当且仅当`prefix[r] == prefix[l-1]`。 因此，问题就变成了找到两个相等的前缀值，并且它们的索引之间的距离最大。 

我们可以通过存储每个前缀和值出现的最早位置来解决这个问题。 当我们再次看到相同的前缀和时，我们计算与其第一次出现的距离并更新答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 前缀和 + hashmap | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 通过处理将字符串转换为运行平衡`U`作为+1和`D`作为-1。 我们维护一个变量`pref`从 0 开始。这将问题转化为检测相等的前缀和。 
2.初始化字典`first_pos`将前缀和值映射到它们出现的最早索引。 我们设定`first_pos[0] = 0`在处理之前，因为开始之前的零和允许子数组从索引 1 开始。 
3. 从左到右迭代字符串，更新`pref`在每个位置。 加工后位置`i`,`pref`表示以 结尾的前缀的余额`i`。 
4.如果`pref`之前已经见过，计算段长度`i - first_pos[pref]`如果这个更大，则更新答案。 这是有效的，因为相等的前缀和意味着它们的索引之间存在零和段。 
5. 如果`pref`以前没见过，商店`first_pos[pref] = i`。 我们只存储第一次出现的情况，以最大化以后的距离，因为以后的出现只会缩短可能的段。 
6. 处理完整个字符串后，答案就是找到的最大平衡段长度。 

### 为什么它有效

 前缀和变换将整个问题编码为相等比较。 每个平衡段完全对应于具有相同前缀和值的两个索引。 通过跟踪每个前缀和的最早出现时间，我们确保每当我们重新访问该和时，我们都会形成以当前索引结尾且净余额为零的最长可能段。 这保证了每个有效段仅被考虑一次，并且捕获其中最长的段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input().strip())
        s = input().strip()

        first_pos = {0: 0}
        pref = 0
        ans = 0

        for i, ch in enumerate(s, start=1):
            if ch == 'U':
                pref += 1
            else:
                pref -= 1

            if pref in first_pos:
                ans = max(ans, i - first_pos[pref])
            else:
                first_pos[pref] = i

        print(ans)

if __name__ == "__main__":
    solve()
```核心实现选择是循环中从 1 开始的索引。 这自然地与前缀定义对齐，其中位置 0 表示空前缀，允许干净的减法`i - first_pos[pref]`无需逐一调整。 

我们也避免更新`first_pos`在第一次出现之后，这是至关重要的。 覆盖它会破坏形成最大长度段的可能性。

    import sys
    input = sys.stdin.readline

 ## 边缘情况

 一个没有的字符串`U`或没有`D`是最重要的退化情况。 用于输入`DDDD`，前缀和只会减少，不会重复，因此字典永远不会产生匹配，答案仍为 0。该算法正确地避免了误报，因为在初始 0 之后永远不会出现前缀和相等的情况。 

像这样的案例`UDUDUD`重复返回先前看到的前缀和。 每次返回都会生成一个以当前索引结尾的候选段，并且由于仅存储最早出现的段，因此始终会考虑以每个位置结尾的最长段。 

混合块的情况，例如`UUDDUD`表明最佳段可能在字符串的中间开始和结束，不一定与块边界对齐。 前缀和相等自然地处理这个问题，无需特殊的大小写。
