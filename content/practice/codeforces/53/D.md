 ## 解决方案
 ## 问题理解

 我们有两个数组代表学生在一行中的顺序。 大批`a`是所需的排列，数组`b`是目前的安排。 在一次操作中，我们可以交换两个相邻的学生。 我们必须输出任意相邻交换序列`b`进入`a`。 

棘手的部分是高度不一定是唯一的。 两个学生可能具有相同的身高，因此我们不能简单地匹配值而不考虑哪个事件对应于哪个位置。 

约束足够小以允许二次算法。 自从`n ≤ 300`，甚至一个`O(n^2)`或者`O(n^3)`解决方案很容易符合限制。 将一种排列变换为另一种排列所需的相邻交换的最大数量最多为`n(n-1)/2`，这对于`n = 300`等于`44850`，远低于允许的`10^6`运营。 

当存在重复值时，粗心的实现可能会失败。 考虑：```
a = [1, 2, 1]
b = [1, 1, 2]
```如果我们贪婪地匹配第一个`1`在`a`与第一个`1`在`b`，那很好。 但如果我们以后搜索不正确，我们可能会移动错误的出现并破坏已经固定的位置。 

当所需的值已经存在于数组中的较早位置时，会出现另一种微妙的情况：```
a = [2, 1, 2]
b = [2, 2, 1]
```固定位置时`2`，我们必须只在不固定的后缀中搜索。 否则我们可能会意外地扰乱已经正确的第一个位置。 

最小的情况也很重要：```
n = 1
a = [5]
b = [5]
```答案必须包含零交换。 一些实现忘记处理这个问题并尝试无效的邻居操作。 

## 方法

 最直接的想法就是暴力模拟。 对于每个职位`i`，我们尝试放置`a[i]`进入数组内的该位置`b`。 我们搜索第一次出现的`a[i]`向右某处，然后反复向左交换，直到到达位置`i`。 

这是可行的，因为相邻的交换让我们可以逐步移动任何元素。 一旦定位`i`包含正确的值，我们再也不会碰它。 

最坏情况下的交换总数是二次方。 例如，反转不同值的数组需要大约`n^2 / 2`互换。 和`n = 300`，这是完全安全的。 

更简单的暴力方法会重复扫描整个阵列以查找不匹配并执行随机本地修复。 这可能会降低立方复杂度，因为每次校正可能需要另一次完整扫描。 和`n = 300`，即使这样可能仍然会过去，但它不必要地混乱并且更难以推理。 

关键的观察结果是相邻的交换自然支持从左到右的固定过程。 一旦我们将正确的值放在位置上`i`，后面的操作只发生在右边`i`，因此前缀永远保持正确。 

这给出了一个干净的贪婪算法：

 1. 从左到右处理位置。 
2. 在后缀中找到所需的值。 
3. 使用相邻的交换将其向左冒泡。 

由于每次操作都严格改进固定前缀，因此算法总是会结束。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 随机暴力修正 | O(n3) | O(1) | O(1) | 不必要的缓慢 |
 | 贪婪相邻冒泡| O(n²) | O(1) 不包括答案存储 | 已接受 |

 ## 算法演练

 1. 从第一个位置开始，从左到右遍历数组。 
2、对于职位`i`，检查是否`b[i]`已经等于`a[i]`。 
3. 如果该值已经正确，则继续到下一个位置。 
4. 否则，搜索第一个索引`j ≥ i`这样`b[j] == a[i]`。 

我们只在后缀中搜索，因为之前的位置`i`已经固定，绝不能再改变。 
5. 将元素移动到位置`j`朝向`i`使用相邻的交换。 

对于每个职位`k`从`j-1`下降到`i`：

- 交换`b[k]`和`b[k+1]`- 记录操作`(k+1, k+2)`在从 1 开始的索引中
 6. 在这些交换之后，位置`i`现在包含`a[i]`。 
7. 继续，直到每个位置都固定。 

### 为什么它有效

 加工后位置`i`, 前缀`b[0..i]`变得与`a[0..i]`。 

该算法再也不会触及此前缀，因为未来的互换仅发生在大于或等于当前索引的头寸内。 由于数组包含相同的多组值，因此每个步骤所需的值必须存在于剩余后缀中的某个位置。 

通过归纳，每个位置最终都会变得正确，所以最终的数组等于`a`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    ops = []

    for i in range(n):
        if b[i] == a[i]:
            continue

        j = i
        while b[j] != a[i]:
            j += 1

        while j > i:
            b[j], b[j - 1] = b[j - 1], b[j]
            ops.append((j, j + 1))
            j -= 1

    print(len(ops))
    for x, y in ops:
        print(x, y)

solve()
```外循环从左到右固定位置。 迭代开始时`i`，每个早期的位置都已经是正确的。 

搜索循环找到第一次出现的`a[i]`在不固定的后缀中。 使用第一次出现就足够了，因为相等的值是可以互换的。 我们只关心一个正确的副本到达位置`i`。 

冒泡循环一一执行相邻的交换。 由于该问题明确要求相邻交换，因此我们必须单独模拟每个移动并将其存储。 

操作索引以从 1 开始的形式存储，因为 Codeforces 在输出中使用从 1 开始的索引。 这是一个很容易犯差点错误的地方。 在数组内部我们使用基于 0 的索引，但是位置之间的交换`j-1`和`j`对应输出`(j, j+1)`。 

交换次数永远不会超过`n(n-1)/2`，因此存储操作的内存使用量仍然很小。

 ## 边缘情况

 考虑重复值的情况：```
a = [1, 2, 1]
b = [1, 1, 2]
```在位置`0`，该值已经是正确的。 在位置`1`，我们需要`2`。 该算法仅在后缀中搜索并找到`2`在索引处`2`。 一个相邻的交换产生：```
[1, 2, 1]
```已经正确的第一位置永远不会改变。 

现在考虑：```
a = [2, 1, 2]
b = [2, 2, 1]
```第一位置立即固定。 加工位置时`1`，算法从索引中搜索`1`继续并发现`1`在索引处`2`。 交换位置`2`和`3`给出了正确的安排。 

如果我们允许搜索较早的位置，我们可能会意外地移动固定前缀并破坏正确性。 

最后，最小的可能输入：```
n = 1
a = [7]
b = [7]
```外循环运行一次。 由于值已经匹配，因此不添加任何操作。 算法正确打印`0`。
