 ## 解决方案
 ## 问题理解

 我们得到一个无向连通图，表示交叉点之间的道路。 市长想要删除一些道路，以便剩余的图变成一棵树，这意味着它保持连接并准确包含`n - 1`边缘。 在所有这样的生成树中，我们只关心那些恰好包含`k`树叶。 叶子是一个顶点，其在树内的度数等于`1`。 

任务是计算原始图有多少生成树`k`树叶。 

图很小，最多只有`10`顶点。 这立即表明子集上的指数算法是可能的。 周围的状态空间`2^10 = 1024`很小。 甚至`3^10`或者`10 * 2^10 * 2^10`动态规划风格可以轻松适应。 

困难不在于连接检查本身。 真正的挑战是在跟踪顶点度数的同时计算生成树，因为叶子的数量取决于最终的度数分布。 

一个简单的解决方案会枚举每个子集`n - 1`边并检查它是否准确地形成生成树`k`树叶。 问题是该图可能包含最多`45`边缘。 子集的数量变为：$$\binom{45}{9} \approx 8.8 \times 10^8$$这在期限内是完全不可能的。 

有几种微妙的情况会破坏粗心的解决方案。 

假设图本身已经是一棵树。```
4 3 3
1 2
2 3
2 4
```只有一棵生成树，即图本身，并且它恰好具有三个叶子。 正确答案是`1`。 假设每个顶点都以叶子开始，然后在添加边时删除叶子，这样一个有缺陷的实现很容易错误地计算中心顶点。 

另一个危险的情况是循环。```
4 4 2
1 2
2 3
3 4
4 1
```循环的每个生成树都是一条路径，并且四个顶点上的每条路径恰好有两个叶子。 正确答案是`4`，因为删除任何一条边都会得到一棵有效的树。 如果连接处理错误，很容易计算出断开的森林。 

增量构建树木时会出现第三个陷阱。 考虑：```
5 6 2
1 2
1 3
1 4
1 5
2 3
4 5
```生成树在构建过程中可能会暂时包含许多叶子，但在添加未来的边之后，其中一些叶子会消失。 任何过早贪婪地固定叶子数量的 DP 都会失败。 

核心问题是，度信息只有在整棵树构建完成后才是最终的。 

## 方法

 蛮力方法很简单。 我们尝试尺寸边缘的每个子集`n - 1`。 对于每个子集，我们检查它是否形成连通图。 由于连通图与`n - 1`边自动成为一棵树，然后我们计算有多少个顶点有度数`1`。 如果该计数等于`k`，我们在答案中加一。 

这是可行的，因为生成树的定义很容易验证。 问题是子集的数量。 在最坏的情况下我们选择`9`边缘出`45`，甚至在执行连接检查之前就已经有近十亿个组合。 

的小值`n`表明状态表示的中心应该是顶点，而不是边。 一棵树有一个非常有用的属性：如果我们将其扎根并一一显示顶点，则每个新添加的顶点都通过一条边连接到已构建的部分。 

该观察结果将问题转化为 DP 子集。 

我们逐步构建连接的诱导结构。 每时每刻我们都坚持：

 - 哪些顶点已经位于当前连接的组件内，
 - 哪些顶点目前在叶子方面具有奇怪的状态，
 - 有多少顶点已经成为内部顶点。 

关键技巧是使用位掩码对度奇偶校验进行编码，同时一次一个边缘地生长树。 每当我们附加一个新顶点时`v`到现有顶点`u`：

 -`v`从学位开始`1`，所以它变成了一片叶子，
 -`u`额外获得一个学位，因此其叶子/内部状态可能会发生变化。 

这种本地更新正是使动态编程成为可能的原因。 

避免多次计算同一棵树的标准方法是将每棵树的最小编号顶点作为根，并且只允许添加较大顶点的过渡。 该规范排序会自动删除重复项。 

得到的 DP 大致有：$$2^n \times 2^n$$州，这是很小的`n ≤ 10`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O\left(\binom{m}{n-1} \cdot (n+m)\right)$|$O(n+m)$| 太慢了|
 | 最佳 |$O(3^n \cdot n^2)$|$O(2^n \cdot n)$| 已接受 |

 ## 算法演练

 我们使用经典的连通子集 DP 来生长有根树。 

让`dp[mask][leafMask]`表示顶点集为的不同树的数量`mask`，并且当前的叶子正是里面的顶点`leafMask`。 

一个顶点属于`leafMask`如果它的当前度数等于`1`。 

### 1. 从每一个可能的根开始

 对于每个顶点`r`，初始化：```
dp[1 << r][0] = 1
```单个孤立顶点有度数`0`，不是学位`1`，所以它还不是叶子。 

我们还强制执行`r`是最终树中的最小顶点。 稍后的过渡仅添加大于的顶点`r`。 这可以防止从不同的根多次计算同一棵树。 

### 2. 展开连通子集

 对于每个当前子集`mask`，尝试添加一个新顶点`v`不在里面`mask`。 

新的顶点必须通过一些边连接`(u, v)`在哪里`u`已经属于`mask`。 

这会自动保留连接。 

### 3.更新叶子集

 安装时`v`到`u`：

 -`v`获得学位`1`，所以它变成了一片叶子，
 -`u`增加其度数`1`。 

对的影响`u`取决于其旧学位类别。 

如果`u`以前不是一片叶子，那么在获得一个额外的边缘后，它仍然不是一片叶子。 

如果`u`以前是一片叶子，那么它的度数从`1`到`2`，所以它不再是一片叶子。 

这种更新可以完全用位运算来表示。 

### 4. 过渡到新状态

 构造：```
newMask = mask | (1 << v)
```然后修改`leafMask`：

 - 切换`u`如果它以前是一片叶子，
 - 添加`v`作为一片叶子。 

将 DP 值添加到新状态中。 

### 5. 以全面罩完成

 处理完所有子集后，每个生成树只出现一次。 

对于每个州：```
mask == (1 << n) - 1
```如果满足以下条件，则进行计数：```
popcount(leafMask) == k
```所有这些状态的总和就是答案。 

### 为什么它有效

 在每次转换时，我们恰好添加一个新顶点和一条将其连接到现有连接组件的新边。 从单个顶点开始并重复此过程总是会生成一棵树。 

相反，通过重复删除最大的非根顶点，可以唯一地重建每棵有根树。 这意味着每个有效的生成树都对应于一个 DP 转换序列。 

叶子遮罩保持正确，因为在过渡期间唯一改变的顶点度数是父级`u`和新附加的顶点`v`。 所有其他顶点保持相同的度数。 更新规则与树度的演变完全匹配。 

由于每个生成树只生成一次，并且我们只计算那些完全符合的生成树`k`离开，算法是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    adj = [[False] * n for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u][v] = True
        adj[v][u] = True

    FULL = (1 << n) - 1

    ans = 0

    for root in range(n):
        dp = [[0] * (1 << n) for _ in range(1 << n)]

        dp[1 << root][0] = 1

        for mask in range(1 << n):
            if not (mask & (1 << root)):
                continue

            for leaf_mask in range(1 << n):
                cur = dp[mask][leaf_mask]

                if cur == 0:
                    continue

                for v in range(root + 1, n):
                    if mask & (1 << v):
                        continue

                    for u in range(n):
                        if not (mask & (1 << u)):
                            continue

                        if not adj[u][v]:
                            continue

                        new_mask = mask | (1 << v)

                        new_leaf = leaf_mask

                        if leaf_mask & (1 << u):
                            new_leaf ^= (1 << u)

                        new_leaf |= (1 << v)

                        dp[new_mask][new_leaf] += cur

        for leaf_mask in range(1 << n):
            if leaf_mask.bit_count() == k:
                ans += dp[FULL][leaf_mask]

    print(ans)

solve()
```邻接矩阵使边存在检查的时间恒定。 自从`n`只是`10`，这比该 DP 的邻接表更简单、更快。 

外层循环固定树的最小顶点。 这是关键的重复删除技巧。 处理根时`r`，我们只添加索引大于的顶点`r`。 每棵生成树都有一个最小的顶点，因此每棵树都被精确计数一次。 

DP 状态存储当前的顶点集和精确的叶子集。 一个常见的错误是试图只存储叶子的数量。 这会失败，因为当一个顶点稍后收到另一条边时，它可能不再是叶子。 算法需要准确地知道当前哪些顶点有度数`1`。 

转换逻辑很微妙。 新添加的顶点总是成为叶子，因为它的度数恰好是`1`。 如果父顶点以前有度数，则它可能会失去叶子状态`1`。 使用异或来删除`u`来自叶子集很方便，因为我们只在以下情况下执行它：`u`已经在叶子面膜里面了。 

内存使用量仍然很小，因为：$$2^{10} \times 2^{10} = 1,048,576$$状态，很容易适合 Python 的内存。

 ### 示例 1

 输入：```
3 3 2

```三角形的所有生成树都是长度为二的路径。 

| 步骤| 面膜| 叶面膜| 意义|
 | ---| ---| ---| ---|
 | 从 1 开始 | 001| 000 | 000 单根|
 | 通过 1 加 2 | 011| 010| 顶点 2 成为叶子 |

 | 步骤| 面膜| 叶面膜| 意义|
 | ---| ---| ---| ---|

 正好有三棵生成树，每棵生成树都有两片叶子，所以答案是`3`。 

此跟踪显示叶状态如何动态变化。 一个顶点可以暂时是一片叶子，然后不再是一片叶子。 

### 示例 2

 输入：```
4 4 2
1 2
2 3
3 4
4 1
```这张图是一个循环。 

| 步骤| 面膜| 叶面膜| 添加边缘 |
 | ---| ---| ---| ---|
 | 0001| 0000 | 0000 开始| |
 | 0011| 0010| 1-2 | 1-2 |
 | 0111| 0100 | 0100 2-3 | 2-3 |
 | 1111 | 1111 1000 | 1000 3-4 | 3-4 |

 最终的叶子是顶点`1`和`4`。 

从循环中删除任何一条边都会给出一条路径，因此总答案是`4`。 

这个例子证实了 DP 永远不会创建循环。 每次转换都会引入一个新顶点。

 ## 边缘情况

 考虑已经是树的图：```
4 3 3
1 2
2 3
2 4
```算法从最小的根、顶点开始`1`。 它逐渐增加`2`， 然后`3`， 然后`4`。 顶点`2`连接到后最初变成叶子`1`，但稍后当顶点时失去叶子状态`3`和`4`附加到它。 最终的叶子面膜恰好包含`{1, 3, 4}`。 不存在替代结构，因此答案变为`1`。 

现在考虑循环：```
4 4 2
1 2
2 3
3 4
4 1
```DP 只允许添加不在当前子集中的顶点。 这意味着任何转变都无法形成循环。 每个完成的结构自动包含准确的`n - 1`边并保持连接，因此每个最终状态都是一棵有效的树。 

最后，考虑叶子状态反复变化的情况：```
5 4 4
1 2
1 3
1 4
1 5
```这是一颗以`1`。 在构造过程中，顶点`1`添加一个邻居后首先成为叶子，然后一旦另一个邻居附加，立即停止成为叶子。 该算法通过叶掩码更新自然地处理这个问题。 最后的叶子完全一样`{2,3,4,5}`，给出答案`1`。
