 ## 解决方案
 ## 问题理解

 给定一个长度为 n 的排列，并且允许我们最多应用 k 个局部操作。 每个操作都针对一对相邻位置。 我们交换两个元素，但交换有一个特殊的副作用：如果交换之前的左侧元素小于右侧元素，则交换后该左侧元素将从序列中删除。 否则，如果左边的元素更大，则交换是纯粹的交换，不会有元素消失。 

因此，每次移动要么仅对两个邻居进行重新排序，要么对它们进行重新排序并恰好删除一个值，特别是在交换之前该对增加时删除较小的值。 

目标是应用最多 k 个这样的操作，以便最终序列尽可能短。 在所有具有最小可能长度的序列中，我们必须输出字典顺序最小的序列。 

关键的困难在于操作同时影响排序和长度，并且交换的效果取决于两个元素当时的局部关系，而不是它们原来的位置。 

约束 n, k ≤ 10^6 强制采用线性或近线性解。 任何显式模拟交换的方法都会太慢，因为单个元素可能会在数组中移动多次，从而在最坏的情况下导致二次行为。 

幼稚的策略会尝试通过扫描有效货币对并应用交换来贪婪地模拟操作。 这会失败，因为每个操作都会更改数组的整个结构，并且重复重新扫描将花费 O(nk)。 

第二个天真的想法是，每当我们看到相邻对不断增加时，就将每个操作视为删除机会。 这也是不正确的，因为两个元素是否相邻取决于之前的交换，因此局部贪婪并不稳定。 

一个小但重要的边缘案例说明了为什么天真的贪婪会失败。 考虑数组`[3, 1, 2]`k = 1。如果我们只看相邻的递增对，我们会看到`1 < 2`，所以我们可以删除`1`，生产`[3, 2]`。 但更好的使用操作是先交换`3`和`1`（不删除），然后应用删除`1 < 2`重新排列后，这可能会根据未来的步骤产生不同的最佳结构。 这表明决策时的邻接不是正确的抽象。 

核心挑战是操作既可用于重新定位元素也可用于删除元素，但只有删除才能改善目标。 任务是决定哪些元素值得删除。 

## 方法

 暴力法直接模拟该过程。 在每一步中，我们扫描数组，选择任何有效位置 i，应用操作，更新数组，并重复最多 k 次。 每个操作都可能会移动元素，因此维护邻接性需要实际的数组更新。 在最坏的情况下，每个操作的成本为 O(n)，从而导致 O(nk)，这远远超出了 k 高达 10^6 的限制。 

关键的观察是，不删除任何内容的交换是纯粹的重新排列。 它们仅用于将某些对组合在一起，以便删除成为可能。 一旦我们认识到操作的唯一有利可图的部分是删除递增对中的左侧元素，我们就可以将该过程重新解释为有选择地删除元素，同时保留剩余元素的相对顺序。 

这将问题简化为构造原始排列的子序列：我们最多可以删除 k 个元素，但删除受到以下事实的限制：只有当元素在删除时成为递增相邻对的左元素时才能删除。 交换的重新排列能力使我们最终能够在有利的时候创建这些邻接，因此真正的限制变成了预算删除而不是几何约束。 

这导致使用单调结构的贪婪构造。 我们从左到右构建最终序列，维护一堆保留的元素。 当我们看到一个新元素时，我们将它与最后保留的元素进行比较。 如果最后保留的元素较小并且我们仍然有删除预算，我们更愿意删除它，因为较早删除较小的元素可以提高字典顺序并缩短序列。 否则，我们保留当前元素。 

蛮力通过显式模拟本地交换来工作，但它会失败，因为它会在每次操作后重新计算结构。 只有删除才重要的观察结果使我们能够将所有交换行为折叠成具有受控删除数量的单个线性传递。

 ## 算法演练

 我们从左到右处理排列，同时维护一个表示最终答案的当前最佳可能前缀的堆栈。 

1. 从一个空堆栈和解释为删除预算的 k 个可用操作开始。 
2. 对于排列中的每个元素 x，尝试将其插入堆栈，同时保留最佳结构。 在插入 x 之前，将其与堆栈中的最后一个元素进行比较。 如果最后一个元素小于 x 并且我们仍有剩余预算 k，则删除最后一个元素而不是保留它。 每次删除对应于花费一次操作来消除按字典顺序局部可改进的元素。 
3. 当栈非空、k 为正且栈的最后一个元素小于 x 时，重复上一步。 这确保我们删除所有当前有害的较小元素，如果保留这些元素，则会恶化字典顺序。 
4. 当不再有任何删除是有益的之后，将 x 追加到堆栈中。 
5. 继续，直到处理完所有元素。 
6. 最后的堆栈就是答案。

这一贪婪删除步骤正确的原因是，此处删除的任何元素都可以在以后通过重新排列操作删除。 延迟删除无济于事，因为将较小的元素保留在较大的元素之前只会恶化字典顺序，并且不会创建以后无法实现的新的有益结构。 

它之所以有效的原因来自于交换属性。 假设存在一个最优策略，其中较小的元素保留在最终序列中，而其右侧存在较大的元素。 我们总是可以交换角色：使用一项操作，我们可以将它们重新排列为相邻的，然后删除较小的一个。 这永远不会增加长度并改善字典顺序，因此任何最佳解决方案都可以转换为这样的解决方案：删除总是贪婪地应用于被较大元素阻塞的较小元素。 这确保基于堆栈的构造永远不会丢弃最佳解决方案中所需的东西。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    p = list(map(int, input().split()))
    
    stack = []
    
    for x in p:
        while k > 0 and stack and stack[-1] < x:
            stack.pop()
            k -= 1
        stack.append(x)
    
    print(len(stack))
    print(*stack)

if __name__ == "__main__":
    solve()
```该解决方案是围绕单个单调堆栈构建的。 每个元素被保留或删除，取决于是否可以使用剩余操作有利地删除它。 while 循环是关键部分：它确保在预算允许的情况下立即删除任何阻碍更好词典前缀的较小元素。 

条件`stack[-1] < x`准确地捕捉了保留前一个元素对于字典顺序和最终长度来说都更糟糕的情况。 预算 k 确保我们不会超过允许的操作数量。

 ## 边缘情况

 对于严格递增的序列，原则上每个相邻对都可以删除，但该算法最多只能删除 k 个元素。 用于输入`[1,2,3,4]`当 k = 2 时，堆栈移除`1`加工时`2`，然后删除`2`加工时`3`，离开`[3,4]`。 这符合始终尽早删除最小可用元素的最佳策略。 

对于像这样的严格递减序列`[5,4,3,2,1]`，不会发生删除，因为没有元素满足递增邻接条件。 堆栈只是增长，并且 k 从未被使用。 

对于交替峰，例如`[1,3,2,4,3,5]`，只要新的大元素在较小的保留元素之后到达，就会发生删除。 该算法正确地优先考虑删除较早的较小值，从而产生紧凑的高值前缀。
