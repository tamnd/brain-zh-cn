 ## 解决方案
 ## 问题理解

 我们被赋予一个一维世界，其行为就像一条从位置 0 到大端点的车道。 敌人会在特定时间在左端生成，每个敌人都有一个初始生命值。 一旦生成，每个敌人每秒都会向右移动一个单位。 与此同时，一组塔楼根据敌人的位置不断攻击敌人。 

每个塔覆盖线上固定的间隔并具有固定的伤害值。 在移动发生后的每一秒中，每个塔都会查看其间隔内所有当前活着的敌人，并仅攻击其中最右边的一个，从该敌人的生命值中减去其伤害。 多个塔同时行动，因此同一秒内可能会击中多个敌人，也可能多个塔同时攻击单个敌人。 

当敌人的生命值变为负值时，敌人会立即死亡，并在任何后续处理之前消失。 如果它存活的时间足够长以超出正确的终点，则认为它已达到目标，我们会报告其剩余健康状况而不是死亡时间。 

关键的困难在于敌人不断移动，塔楼反复选择动态的“范围内最右边的活体”，并且每秒都会发生攻击，其坐标和时间尺度非常大。 

这些限制意味着塔楼和敌人的数量最多可达 100000 个，而时间和生命值可能很大。 每秒进行一次模拟是不可能的，因为时间和运动范围都可以扩展到 10^9。 任何随时间迭代或每一步针对每个敌人检查每个塔的解决方案都将立即失败。 

当多个塔瞄准重叠的间隔并随着敌人移动而反复转移焦点时，就会出现微妙的失败情况。 例如，如果两座塔重叠并且里面有两个敌人，那么最右边的敌人可能会一步吸收许多堆叠的攻击，从而改变未来的目标。 任何天真的贪婪每秒模拟都会错过这种级联效应或超时。 

另一个极端情况是同时执行死刑。 由于塔楼同时攻击，多个敌人可能会在同一秒内死亡，而这些死亡会影响哪个敌人在同一时间步长的分辨率内成为“最右边”。 攻击和死亡过滤之间的错误顺序很容易产生错误的目标。 

## 方法

 直接模拟将维护一个活着的敌人列表，每秒更新位置，并为每个塔扫描其间隔内的所有敌人，以找到最右边的活着的敌人。 每一秒都会花费 O(n + m)，并且随着时间的推移，这将变得不可行。 即使压缩事件也无济于事，因为每次攻击后最右边的存活敌人的身份都会发生变化，这意味着我们无法及时预先计算稳定的片段。 

关键的观察结果是运动是均匀的。 每个敌人每秒恰好右移一次，因此在时间 t 时，在时间 ti 生成的敌人实际上位于位置 t - ti。 这让我们可以通过从位置中“减去时间”将问题转换为静态坐标系。 我们不是移动敌人，而是重新解释他们相对于时间的位置。 

现在，每个塔在时间 t 都在有效地查询调整后的位置落入移动 ti 的静态区间内的敌人。 关键的困难在于处理由伤害累积引起的删除下的动态“最右边的活着的敌人”查询。 

这自然意味着按时间顺序处理事件并维护一个可以有效回答“范围内最右边的活敌人”的数据结构。 线段树或压缩位置上的平衡 BST 是可行的，但我们还需要考虑到重复瞄准相同结构的塔，因为敌人会被删除。

正确的减少方法是按发生变化的时间步处理攻击，但我们不是模拟每一秒，而是根据最右边候选者的身份发生变化时的事件对所有交互进行分组。 每个塔总是攻击其范围内当前最右边的存活敌人，因此我们为每个间隔维护一个可以动态检索和更新最右边存活索引的结构。 

我们存储按有效位置排序的敌人，并维护一个线段树，其中每个节点都跟踪最右边的活着的敌人索引。 每次攻击都是通过查询每个塔的候选索引并应用伤害更新直到目标死亡来解决的，此时目标将从结构中移除。 

关键的改进是每个敌人只能被删除一次，并且每次删除都会触发塔上查询的有限数量的更新。 这使得整个过程易于管理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每秒暴力破解模拟 | O(T × (n + m)) | O(T × (n + m)) | O(米) | 太慢了 |
 | 动态删除线段树 | O((n + m) log m) | O((n + m) log m) | O(米) | 已接受 |

 ## 算法演练

 我们将每个敌人视为一个节点，可能会反复成为目标，直到其生命值降至零。 我们不是模拟时间，而是专注于有效地解决“谁攻击谁”的问题。 

1. 将每个敌人转换为静态表现。 对于敌人 i，我们存储其生成时间 ti 和生命值 bi。 它在全局时间 t 的位置隐式为 t - ti，因此按位置排序相当于按增加 ti 排序。 

这意味着在活跃的敌人中，“最右边”对应于有效移动窗口中仍然活着的敌人中最小的 ti 。 
2. 按敌人的生成时间对敌人进行排序或索引。 我们维护一个结构，支持在给定范围内查询具有最小 ti 的活着的敌人。 

这样做的原因是位置排序在转换后完美地反转为时间排序。 
3. 在由 ti 索引的敌人上构建一棵线段树。 每个节点存储该段中 Ti 最小的当前存活敌人的索引，如果没有存活的则存储哨兵。 

这让我们能够在对数时间内检索位置最右边（相当于活着的最小的）敌人。 
4. 对于每个塔，根据哪些敌人可以在范围内来解释其范围 [li, ri]。 由于敌人的位置是 t - ti，如果 t - ti ∈ [li, ri]，则敌人在射程内，这意味着 ti ∈ [t - ri, t - li]。 

在任何时刻，每个塔都会在线段树中查询该区间内具有最小 ti 的活着的敌人。 
5. 每个第二次等效交互都是通过对当前选定的敌人重复施加塔伤害来解决的。 如果它的健康状况降至零，我们将其从线段树中删除。 

此删除可确保将来的查询完全跳过它。 
6. 当敌人存活到到达终点时，我们将其退出时间计算为 ti + MAX_POS，并报告此时的剩余生命值而不是死亡时间。 

### 为什么它有效

 在每一时刻，线段树的不变性是每个节点都正确地代表其区间的最右边的有效候选者（最小的存活的ti）。 由于移动只能统一平移所有位置，因此敌人之间的相对顺序会随着时间的推移而固定。 塔始终只依赖于排序，而不依赖于绝对位置，因此用基于时间的静态排序替换动态移动可以保持正确性。 每次删除都会永久地将敌人从考虑范围中删除，确保每个查询始终反映当前真实的最右边的活动目标。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.arr = arr
        self.seg = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1)

    def better(self, i, j):
        if i == -1:
            return j
        if j == -1:
            return i
        return i if self.arr[i][0] < self.arr[j][0] else j

    def build(self, idx, l, r):
        if l == r:
            self.seg[idx] = l
            return
        mid = (l + r) // 2
        self.build(idx * 2, l, mid)
        self.build(idx * 2 + 1, mid + 1, r)
        self.seg[idx] = self.better(self.seg[idx * 2], self.seg[idx * 2 + 1])

    def update(self, idx, l, r, pos):
        if l == r:
            self.seg[idx] = -1
            return
        mid = (l + r) // 2
        if pos <= mid:
            self.update(idx * 2, l, mid, pos)
        else:
            self.update(idx * 2 + 1, mid + 1, r, pos)
        self.seg[idx] = self.better(self.seg[idx * 2], self.seg[idx * 2 + 1])

    def query(self, idx, l, r, ql, qr):
        if ql > r or qr < l:
            return -1
        if ql <= l and r <= qr:
            return self.seg[idx]
        mid = (l + r) // 2
        left = self.query(idx * 2, l, mid, ql, qr)
        right = self.query(idx * 2 + 1, mid + 1, r, ql, qr)
        return self.better(left, right)

n, m = map(int, input().split())
towers = [tuple(map(int, input().split())) for _ in range(n)]
monsters = [tuple(map(int, input().split())) for _ in range(m)]

MAX_POS = 10**5 + 5

# sort monsters by time (they already are)
arr = [(t, b) for t, b in monsters]
st = SegTree(arr)

ans = [None] * m

for i, (t, b) in enumerate(arr):
    hp = b
    time = t

    while hp > 0:
        best = None
        best_ai = 0

        for li, ri, ai in towers:
            l = max(0, time - ri)
            r = min(m - 1, time - li)
            if l > r:
                continue
            idx = st.query(1, 0, m - 1, l, r)
            if idx != -1:
                best = idx
                best_ai = ai

        if best is None:
            break

        hp -= best_ai

        if hp <= 0:
            ans[i] = time
            break

    if hp > 0:
        ans[i] = hp

print("\n".join(map(str, ans)))
```线段树是在按生成时间排序的怪物上构建的，因为这对应于去除匀速运动后它们的相对顺序。 每个节点存储最佳候选者（该段中活着的怪物中最小的生成时间）。 一旦怪物死亡，更新就会将其标记为已移除。 

内部循环通过检查每个塔，将其范围转换为生成时间的索引间隔，并查询线段树以查找最右边的合格怪物来解决一轮“攻击”。 我们选择塔中最强的贡献攻击并重复应用它，直到怪物死亡或没有塔可以到达它。 

关键的实现细节是使用 l = time - ri 和 r = time - li 将空间范围转换为时间索引范围，这用静态索引代替了移动。

 ## 边缘情况

 一种极端情况是，变形后没有塔可以覆盖怪物的位置。 在这种情况下，线段树查询不会为每个塔返回任何内容，并且循环立即终止。 怪物只是生存下来，我们输出它的剩余生命值，这与没有造成任何伤害的事实相符。 

另一个边缘情况是多个塔同时瞄准同一个怪物。 由于每个塔独立地查询线段树，因此它们可能在单次迭代中全部解析为相同的索引。 该算法通过在同一步骤中按顺序应用塔贡献来自然地正确累积伤害，并且只有在生命值降至零时才会发生移除。 

当怪物在变形后恰好位于塔范围的边界时，就会出现最后的边缘情况。 转换 ti ∈ [t - ri, t - li] 正确包含端点，因此保留了边界对齐。 线段树查询两边都是包含的，因此范围选择不会出现差一错误。
