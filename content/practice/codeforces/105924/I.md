 ## 解决方案
 ## 问题理解

 我们得到一个图表，其中 2n 个城市分为两行。 第一行包含标记为 1 到 n 的城市，第二行包含标记为 n+1 到 2n 的城市。 第一行中的每个城市都与第二行中的每个城市相连，因此底层图是两行之间的完全二部图。 

除了这种密集的连通性之外，第一排的每个城市在第二排都有一个特殊的“冲突伙伴”。 形式上，对于第一行中的每个 i，第二行中都有一个唯一的 ai，并且这些 ai 值都是不同的，这意味着这定义了两行之间的完美匹配。 

如果路径包含任何冲突对的两个端点，则该路径被视为无效。 换句话说，如果一条路径访问 i 并且在任何点也访问 ai，则该路径被禁止，无论顺序如何或它们是否连续。 

对于每个查询，我们都会被询问是否存在从起始城市 s 到目标城市 t 且遵守此限制的有效路径。 

这些约束意味着测试用例中的 n 总数可以达到 2×10^5，并且测试用例的数量最多可以达到 10^5。 这立即排除了任何探索路径或针对每个查询执行图形搜索的方法。 在最坏的情况下，即使每个查询的线性 BFS 也会太慢，因为图很密集并且每个查询需要 O(n) 或更多时间。 

主要的微妙之处在于该图几乎是完全连接的，因此可达性并不是真正的瓶颈。 唯一的障碍来自“不能包括匹配对的两个端点”规则。 粗心的方法可能会在跟踪访问的约束时尝试模拟 BFS，但这会错误地使答案取决于非常小的结构条件的情况变得过于复杂。 

一个常见的错误是假设中间节点可能以更复杂的方式阻止连接。 例如，人们可能会认为，如果 s 连接到 ai 并且 t 连接到 i，那么限制可能会强制绕行，从而破坏连接。 实际上，该图是如此密集，以至于我们总是可以围绕禁止对重新路由，除非我们被迫包含单个对的两个端点。 

唯一真正有问题的情况是当 s 和 t 本身形成禁止对时。 

## 方法

 暴力破解的想法是显式地构造图并从 s 到 t 运行受约束的 BFS 或 DFS，并携带一组会使路径无效的禁止顶点。 每个状态都需要记住哪些匹配的端点已经被访问过，因为踏上一个顶点实际上会禁止其伙伴进入路径的其余部分。 这将问题变成了状态爆炸：在完全二部图中，每个步骤都分支为 O(n) 个邻居，并且状态空间将随着访问的顶点数量呈指数增长。 即使没有完整状态跟踪的简化 BFS，每次查询的时间复杂度仍然是 O(n)，对于最多 10^5 次查询来说，这太慢了。 

关键的观察是图结构在两个分区之间最大程度地连接。 顶行中的任意顶点可以一步到达底行中的任意顶点，反之亦然。 因此，路径失败的唯一原因是从 s 到 t 的每条可能的路由都会强制访问冲突对的两个端点。

现在观察到底是什么引发了冲突。 唯一一次我们立即被禁止的情况是路径同时包含 i 和 ai。 如果 s 和 t 本身形成这样的一对，则从 s 到 t 的任何路径都已包含两个端点，因此根据定义它是无效的。 相反，如果 s 和 t 不是匹配对，我们总是可以通过选择避开 s 和 t 的禁止端点的中间顶点来构造长度最多为 2 或 3 的有效路径。 由于相反分区中有 n 个选择，并且每个顶点只有一个禁止伙伴，因此总有一个安全的中介。 

因此，问题归结为检查 s 和 t 是否对应于相同的匹配边。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 带有约束的强力 BFS | 每个查询 O(n) | O(n) | 太慢了 |
 | 使用匹配 | 直接配对检查 O(n) 预处理，O(1) 每个查询 | O(n) | 已接受 |

 ## 算法演练

 1. 建立一个逆映射，使得对于第二行中的每个城市，我们都可以快速找到其在第一行中的匹配伙伴。 这是必要的，因为输入仅给出从第一行到第二行的映射。 
2. 对于每个查询，确定 s 是在第一行还是第二行，并使用适当的映射方向来查找其匹配的伙伴。 此步骤确保我们可以统一推理包含 s 的对。 
3. 检查t 是否恰好是s 的伙伴。 如果是，则从 s 到 t 的任何路径都将包含禁止对的两个端点，这使得该路径根据定义无效。 
4. 如果 s 和 t 不是伙伴，则立即断定存在有效路径。 边的密度保证我们总是可以通过一些中间顶点进行路由，同时避免同时包含任何禁止对。 

### 为什么它有效

 每个城市都参与一对禁止配对，并且这些配对在两方分裂中形成完美匹配。 仅当路径包含任何匹配对的两个顶点时，路径才会变得无效。 由于图在分区之间是完整的，因此我们永远不会被迫包含特定顶点，除非它是起点或目标。 因此，唯一不可逆的冲突是起点和目标本身匹配时，因为连接它们的任何路径都必须包括两个端点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n, s, t = map(int, input().split())
        a = list(map(int, input().split()))

        inv = {}
        for i, v in enumerate(a, start=1):
            inv[v] = i

        def partner(x):
            if 1 <= x <= n:
                return a[x - 1]
            else:
                return inv[x]

        if partner(s) == t:
            out.append("No")
        else:
            out.append("Yes")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案为第二行构建一个逆字典，以便合作伙伴查找可以在两个方向上进行。 辅助函数`partner(x)`将任何节点标准化为其匹配的对应项，无论它属于哪一行。 

最终条件是直接比较：如果目标是源的匹配伙伴，则输出“No”，否则输出“Yes”。 不需要图遍历，因为该结构保证替代路线始终存在。 

## 工作示例

 考虑 n = 2、a = [3, 4] 的情况。 这对是 (1,3) 和 (2,4)。 如果 s = 1 且 t = 4，则伙伴 (1) = 3，因此 t 不是伙伴并且存在有效路径。 

| 步骤| s | t | 合作伙伴 | 决定|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 4 | 3 | 不等于 → 是 |

 现在考虑 s = 1 和 t = 3。这里partner(1) = 3，因此端点形成禁止对。 

| 步骤| s | t | 合作伙伴 | 决定|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 3 | 3 | 等于 → 否 |

 第一条轨迹表明，不匹配的端点通过密集的二分结构保持连接。 第二条跟踪隔离了整个问题中唯一的阻塞配置：单个匹配对的端点。

 ## 边缘情况

 最重要的边缘情况是 s 和 t 形成匹配对时。 在这种情况下，例如 n = 1 且 a = [2]，唯一可能的对是 (1,2)。 如果 s = 1 且 t = 2，partner(1) = 2，则算法立即输出“否”。任何尝试的路径都必然包含两个顶点，这违反了约束。 

另一种边缘情况是当 s 或 t 位于第二行时。 例如，如果在 inv[3] = 1 的系统中 s = 3，则partner(3) = 1。该逻辑仍然可以正确归约，因为我们通过相同的匹配关系对两个端点进行标准化，从而确保行之间的对称性。
