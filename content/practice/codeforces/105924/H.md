 ## 解决方案
 ## 问题理解

 我们的系统有两个相互作用的方面：城市和人群。 有$n$城市，每个城市都有一个成本参数$c_i$， 和$n$居民群体，其中群体$i$包含$b_i$人们。 每个群体都禁止居住在一个城市中，紫禁城映射形成一种排列：每个城市都禁止居住在一个群体中，每个群体都禁止居住在一个城市中。 

每个团体可以将其人员分散到多个城市，只要没有人被分配到该团体的紫禁城即可。 分配完所有人员后，各个城市$i$最终得到一些总人口$d_i$。 城市的不适$i$定义为$c_i \cdot d_i$，目标是尽量减少所有城市的最大不适。 

关键的困难在于，人是可分割的，可以在允许的城市之间任意分布，但每个单位都必须被分配，并且每一对禁止的城市恰好消除了每个城市的一个潜在供应源。 

约束条件很大，总共$n$跨测试用例最多$2 \cdot 10^5$，因此每个测试用例的任何解决方案都必须接近线性或对数线性。 任何涉及每次测试的流量或所有城市对和组之间的二次交互的事情都会太慢。 即使每个测试用例只有一个最大流量也是不可行的。 

微妙的一点是，禁制结构极其规则。 每行（组）恰好有一个禁止列（城市），每一列也恰好有一个禁止行。 这种对称性是避免一般二分流复杂性的主要结构处理。 

一个常见的陷阱是假设每个城市的最终人口被固定为“除了一个群体之外的所有人口”，但这是不正确的，因为每个群体可以在所有允许的城市中任意分配其人口。 另一个错误是假设问题是每个城市独立分解的，但共享的供应约束将所有城市连接在一起。 

## 方法

 直接解释就是流量问题：每个群体都是一个有供给的来源$b_i$，每个城市都是一个具有无限需求的汇，但我们必须尊重目标边界隐含的容量，并且除了每组一对禁止对之外，存在边缘。 测试候选人的答案$X$，我们需要$c_i d_i \le X$， 所以$d_i \le \left\lfloor X / c_i \right\rfloor$。 问题是我们是否可以在不超过这些容量的情况下将所有物资输送到城市，同时尊重禁区。 

暴力解决方案会尝试贪婪地分配人员，甚至构建一个全流网络。 这立即导致二部流$O(n^2)$边缘和潜在的$O(n^3)$或者每次测试都有更糟糕的行为，这太慢了。 

关键的观察结果是，图中唯一的不规则之处是每行和每列有一个禁止边。 这使得结构几乎完全二分，并且当按照尊重容量紧张的顺序处理节点时，这种“几乎完全”约束通常允许贪婪解决方案。 

我们不直接解决流量问题，而是反转视角：认为每个城市的“容量预算”都是有限的$cap_i = \lfloor X / c_i \rfloor$。 我们必须分发所有$b_i$跨城市，使每个城市的总接收量不超过其容量，并分组$i$无法为城市做出贡献$a_i$。 

现在想象一下加工城市从最小容量到最大容量的情况。 小容量城市最难满足，因此必须首先利用最灵活的供应来满足。 每次我们处理一个城市时，我们都会从除禁止的群体之外的所有群体中尽可能多地分配剩余人口，总是首先从最大的剩余供应中获取。 排列约束确保我们需要的唯一临时排除是每个城市一个组，可以在分配期间在本地处理。 

可行性检查变成了排除下的贪婪重新分配，以及二分搜索$X$得出最终答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 直接流动配方|$O(n^3)$每次测试或更差 |$O(n^2)$| 太慢了 |
 | 容量+贪婪排序+二分查找|$O(n \log n \log V)$|$O(n)$| 已接受 |

 ## 算法演练

 我们对待答案$X$作为我们可以验证的值。 对于固定的$X$, 各个城市$i$最多可以接受$cap_i = \lfloor X / c_i \rfloor$人们。 我们检查是否所有$b_i$可以放置在尊重容量和禁止配对的城市中。 

1. 按升序对城市进行排序$cap_i$。 我们这样做是因为容量较小的城市受到的限制最大，必须在灵活供应耗尽之前尽早满足。 
2. 将每组的剩余供应量维持为多重集，由$b_i$。 这代表每个小组还需要分配多少人。 
3. 对于排序后的每个城市，暂时标记其禁区$p(i)$无法完成该城市的任务。 这确保我们永远不会违反该组的约束$p(i)$不能去城市$i$。 
4. 不断向当前城市分配人员，直到其容量被填满或没有有效供应为止。 在每一步中，我们都会选择剩余最大的组$b_j$这个城市并不禁止这样做。 

直觉是，从较大的剩余群体中获取资源可以为未来受限的城市保留灵活性。 小城市先满足，避免了只剩下大的刚性群体，而小容量城市还需要填补的情况。 

1. 减少所选组的剩余数量$b_j$按分配的金额。 如果没有耗尽，它会保留在池中以供以后的城市使用。 
2、完成城市后恢复禁团，前往下一个城市。 

如果在任何时候，即使在耗尽所有有效组之后，我们也无法将城市填满，则配置$X$是不可能的。 

1.二分查找最小$X$可行性检查成功。 

### 为什么它有效

 正确性取决于单调堆积属性。 城市的处理能力是从最紧张到最宽松的，因此任何满足较早城市的分配都不能通过延迟满足来改进，因为后面的城市具有严格更大或相等的容量，因此永远不会产生新的瓶颈。 禁止的约束仅删除每列一行，因此在任何时候，可用供应仍然足够灵活，可以在剩余城市之间重新排列。 贪婪地消耗最大的剩余群体可以为未来的受限步骤保留可行性，因为它可以最大限度地减少供应碎片。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def check(n, a, b, c, X):
    cap = [X // c[i] for i in range(n)]
    rem = b[:]
    # p[i] = index of group forbidden from city i
    p = [0] * n
    for i in range(n):
        p[a[i]] = i

    import heapq
    heap = []
    for i in range(n):
        if rem[i] > 0:
            heapq.heappush(heap, (-rem[i], i))

    # process cities by increasing capacity
    order = sorted(range(n), key=lambda i: cap[i])

    for i in order:
        need = cap[i]
        forbidden = p[i]

        temp = []
        while need > 0 and heap:
            val, idx = heapq.heappop(heap)
            val = -val
            if idx == forbidden or val == 0:
                temp.append((val, idx))
                continue

            take = min(need, val)
            need -= take
            val -= take

            if val > 0:
                temp.append((val, idx))

        for v, idx in temp:
            heapq.heappush(heap, (-v, idx))

        if need > 0:
            return False

    return True

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        a = list(map(lambda x: int(x) - 1, input().split()))
        b = list(map(int, input().split()))
        c = list(map(int, input().split()))

        lo, hi = 0, sum(b) * max(c)
        ans = hi

        while lo <= hi:
            mid = (lo + hi) // 2
            if check(n, a, b, c, mid):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        print(ans)

if __name__ == "__main__":
    solve()
```该实现将可行性检查与对答案的二分搜索分开。 检查功能构建容量限制$X$，从排列中重建禁止映射，然后模拟贪婪分配。 

一个重要的常见实现细节是在分配循环内处理每个城市的禁止组。 该组不能对当前城市做出贡献，即使是暂时的，因此在弹出过程中会跳过它，但会保留在堆中以供以后使用。 另一个微妙之处是，我们在处理每个城市后重新插入临时删除的堆条目； 否则我们将永远错误地失去供应状态。 

二分搜索上限使用总人口乘以最大成本，这是安全的，因为将所有内容分配给最大成本城市始终是目标的上限。

 ## 边缘情况

 当一个城市由于大量数据而导致容量极小时，就会出现严重的边缘情况。$c_i$，而其禁制团体也是最大的贡献者之一。 在这种情况下，如果没有其他群体能够完全补偿，那么贪婪过程就会在该城市失败。 该算法会检测到这一点，因为在处理过程中，所有兼容组在城市容量填满之前就已耗尽，从而立即触发拒绝。 

另一个边缘情况是所有成本都相等。 那么容量仅取决于$X$，并且问题简化为在禁止边缘下分配总和的纯粹可行性。 贪婪顺序仍然有效，因为所有城市的优先级都是相同的，并且任何顺序都会产生相同的可行性结果。 

最后一种边缘情况是一个群体在规模上占主导地位。 由于它只在一个城市被禁止，因此它必须传播到所有其他城市。 基于堆的贪婪确保它在多个城市中逐步耗尽，并且它永远不会阻止较小的群体满足紧张的容量，因为城市是按照容量递增的顺序进行处理的。
