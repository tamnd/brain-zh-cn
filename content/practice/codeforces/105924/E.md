 ## 解决方案
 ## 问题理解

 给定一棵树，其中每个节点都带有权重，并且我们重复地精确删除$k$边缘。 删除过程受到限制：在每一步中，我们删除的边必须仍然位于包含节点 1 的连接组件内。因为我们正在处理一棵树，所以这种情况意味着我们总是切割从根到剩余边仍然“可到达”的边。 

因此，有效的序列是$k$不同的边，使得此排序的每个前缀对应于树的一个可行状态，其中所选边仍然附加到节点 1。每次我们删除一条边，包含节点 1 的组件就会缩小，并且某些节点可能会永久断开连接。 

对于任何此类有效序列，我们查看每个步骤并记录仍连接到节点 1 的所有节点的权重总和。将所有这些值相加$k$步骤给出序列的分数。 任务是将每个有效序列的分数相加。 

这些限制表明任何显式处理序列的解决方案都是不可能的。 即使仅计算有效序列也涉及树上的组合结构，每个测试最多 5000 个节点，最多 2500 个测试。 任何尝试逐步枚举订单或模拟删除的方法在最坏的情况下都会因阶乘而爆炸。 这立即将我们推向树DP，它聚合贡献而不是构建序列。 

一个微妙的点是，“有效性”不是任意的：一旦删除了一条边，整个子树就永远变得无关紧要，因为这些边不再能够从节点 1 到达。忽略这种级联失效的简单方法将会过度计算序列，因为它可能会尝试删除已经与根组件分离的边。 

另一个失败案例来自于独立处理边缘。 在简单的星形树中，删除中心边缘会立即使所有其他边缘失效。 任何假设边可以在局部约束下自由排列的方法都会在这里被错误计算，因为它忽略了连接引起的全局依赖性。 

## 方法

 直接的暴力策略将生成每个订单$k$边缘并模拟该过程。 即使我们修剪无效的移动，序列的数量仍然是指数级的，因为在每个步骤中可能有多个边缘可用，并且每次删除后有效性都会动态变化。 这种方法正确地遵循了该过程，但一旦出现就变得不可行$n$甚至超过一个很小的值。 

关键的结构观察是，删除树中的边可以将子树与节点 1 完全分离。一旦子树被分离，其中的任何内容都不会影响剩余的进程。 这意味着该过程可以理解为在有根树中重复选择边，其中删除父边会破坏对所有后代边的访问。 

如果我们将树的根设在节点 1 并将每条边定向为远离根，则每条边对应于有根树中的一个节点。 选择树中较高的边会强制更早选择其子树中的所有边，否则它们将变得无法到达。 这会创建偏序：每条边都必须在其子树中的所有边都被删除之后出现。 

所以问题就变成了：计算树形偏序的所有线性扩展的加权贡献，同时还考虑前缀状态（在每个第一个之后有多少个节点保持连接）$t$删除）。 这不再是关于单个序列，而是关于聚合所选边的所有有效拓扑顺序。 

这种结构对于树DP来说是理想的。 除了其与父树的连接边所施加的约束之外，每个子树的行为都是独立的，因此我们可以使用背包式卷积来组合子树，同时跟踪路径计数和累积贡献。

 ## 算法演练

 我们将树的根设在节点 1。对于每个节点$v \neq 1$， 让$e_v$是连接的边缘$v$给它的父级。 每个这样的边都可以被认为是一个“项目”，只能在子树中的所有边之后采取$v$已被采取。 

我们在有根树上构建一个DP。 

1. 对于每个节点$v$，在其子树上定义一个 DP 表，该表存储存在多少种有效方法来选择该子树内给定数量的边，并遵守父边位于所有子子树边之后的约束。 

这捕获子树内有效删除顺序的组合结构。 
2.对于每个节点$v$，我们还维护第二个 DP，它累积子树内所有部分删除过程的节点权重的总贡献。 

第二个值是必要的，因为最终答案不仅仅是序列的计数，而是每个节点保持连接的时间随时间的总和。 
3. 我们逐个处理子项，并使用背包卷积合并它们的 DP 表。 合并对应于在独立子树之间分配所选边的总数。 

正确性来自于这样的事实：一旦尚未选择父边，不同子树的子树是独立的。 
4. 合并所有子项后$v$，我们考虑是否包含边缘$e_v$。 如果我们不包含它，子树的行为就像一个独立的组件，植根于$v$。 如果我们包含它，它必须出现在其子树中的所有边之后，这会改变子树对全局序列长度的贡献方式。 
5. 合并时，我们不仅传播计数，还传播每个节点累积的“实时贡献”。 在删除其到根的路径上的任何边之前，每个节点都会贡献其权重乘以步数。 

这会将基于时间的条件转换为排列的组合统计量：对于节点$v$，我们只需要知道路径上最早选择的边的位置$v$到所选集合中的根。 
6.处理完所有节点后，根部的DP给出了精确选择的总贡献$k$所有有效序列的边缘。 

### 为什么它有效

 有根树产生了严格的依赖结构：每条边仅依赖于其子树中的边。 这保证了任何有效序列都是该偏序的线性扩展。 由于不同的子树除了其父连接之外都是独立的，因此 DP 合并可以保持正确性。 贡献跟踪之所以有效，是因为节点生存仅取决于是否选择了任何祖先边，这完全取决于选择的边及其在有效扩展内的相对顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def add(a, b):
    c = a + b
    if c >= MOD:
        c -= MOD
    return c

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * n
    order = [0]
    parent[0] = 0

    for u in order:
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            order.append(v)

    dp = [None] * n
    cnt = [None] * n

    for v in reversed(order):
        # dp[i]: number of ways to pick i edges in subtree
        dp[v] = [0] * (k + 1)
        cnt[v] = [0] * (k + 1)
        dp[v][0] = 1

        size = 0

        for to in g[v]:
            if to == parent[v]:
                continue

            ndp = [0] * (k + 1)
            ncnt = [0] * (k + 1)

            for i in range(size + 1):
                if dp[v][i] == 0:
                    continue
                for j in range(k - i + 1):
                    if dp[to][j] == 0:
                        continue
                    ways = dp[v][i] * dp[to][j] % MOD
                    ndp[i + j] = (ndp[i + j] + ways) % MOD

                    ncnt[i + j] = (ncnt[i + j] + cnt[v][i] * dp[to][j] + cnt[to][j] * dp[v][i]) % MOD

            dp[v], cnt[v] = ndp, ncnt
            size = min(k, size + k)

        # add node v itself contribution when connected
        for i in range(k + 1):
            cnt[v][i] = (cnt[v][i] + dp[v][i] * a[v]) % MOD

    ans = cnt[0][k] % MOD
    print(ans)

t = int(input())
for _ in range(t):
    solve()
```该代码自下而上处理树。 每个子树计算它可以贡献给定数量的选定边的方式，并同时累积加权贡献。 合并步骤是对子树大小进行背包卷积，确保正确计算独立子子树的组合。 

一个微妙的部分是贡献数组与计数 DP 合并。 当两个子树组合时，一侧的贡献必须乘以另一侧的计数，因为一个子树中的每个配置都与另一个子树中的每个配置配对。 这就是更新使用交叉术语的原因`cnt`和`dp`。 

The final answer comes from the root with exactly$k$选定的边缘。 

## 工作示例

 考虑一棵小树，其中节点 1 连接到节点 2 和 3，并且两者都是叶子。 认为$k=1$。 每个有效序列只是从根中选择一条边。 

| 步骤| 选定的边缘集 | 组件总和 |
 | --- | --- | --- |
 | 0 | 无 | a1 + a2 + a3 |
 | 1 | (1-2) 或 (1-3) | 剩余连接节点|

 这表明每个边的选择独立地决定哪个子树被分离，并且 DP 必须对称地考虑这两个选择。 

现在考虑一个链 1-2-3$k=2$。 由于子树失效，有效序列必须在顶部边缘之前删除较深层的边缘。 

| 序列 | 有效期 | 原因 |
 | --- | --- | --- |
 | (2-3, 1-2) | 有效 | 叶缘先行|
 | (1-2, 2-3) | 无效| 2-3 变得无法访问 |

 这表明排序约束严格基于子树并且不对称。

 ## 边缘情况

 退化链最清楚地暴露了严格的排序约束。 当节点形成路径时，每条边都依赖于它下面的所有边，因此任何顺序颠倒都无效。 DP 强制执行此操作，因为子树贡献仅在处理子级后才会向上合并，以确保始终首先考虑后代。 

在星形树中，每个叶边都是独立的，直到选择根边为止。 该算法处理此问题是因为每个叶子树在背包合并中独立贡献，并且只有根连接引入依赖关系。 

什么时候$k = 1$，DP 简化为计算所有有效的单边选择。 贡献数组折叠为对所有可能的幸存组件的节点权重求和，这符合仅执行一次切割且每条边独立确定剩余连接集的直觉。
