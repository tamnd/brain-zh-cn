 ## 解决方案
 ## 问题理解

 我们得到一个包含不同值的初始数组，然后是一系列更新。 每次更新只更改一个位置，并且每次更新后数组仍然包含不同的值。 这会产生一个数组时间线：原始数组，然后每次修改后，直到我们总共有$m+1$版本。 

对于每对版本$A_i$和$A_j$，我们将它们连接起来并计算该组合多重集中出现的不同值的数量。 任务是计算所有版本对的该值的总和。 

重新解释问题的一个有用方法是从重叠的角度进行思考。 如果连接两个数组，则不同元素的数量为$$|A_i| + |A_j| - |A_i \cap A_j|.$$因为每个数组总是有大小$n$，问题就变成：$$n + n - |A_i \cap A_j| = 2n - |A_i \cap A_j|.$$因此，整个任务简化为对所有版本对的交集大小求和。 

这将问题从“计算不同的联合”转变为“跟踪每个值在版本之间持续和重叠的时间”。 

这些限制清楚地表明了幼稚方法失败的原因。 最多可以有$2 \cdot 10^5$跨测试用例的总操作，意味着版本数量很大。 任何直接比较版本对的方法都需要$O(m^2)$，当$m$可以达到$2 \cdot 10^5$。 

一个微妙的边缘情况来自于被删除后重新出现的值。 某个值可能存在于版本 0 中，在某些操作中消失，然后再也不会出现。 另一个值可能会较晚引入并持续存在。 如果我们错误地假设“每个值在每个版本中独立贡献”，我们将重复计算重叠或错过取消。 

一个陷阱的小例子：

 输入：```
n = 2, m = 1
A0 = [1,2]
A1 = [2,3]
```对：

 - (0,0)：2 个不同的
 - (0,1)：3 个不同的
 - (1,1)：2 个不同的

 答案 = 7。 

一种天真的尝试可能会认为“每个操作都会添加一个新值，因此只会累积更改”，但这忽略了交集取决于完整的生命周期重叠，而不仅仅是本地更新。 

## 方法

 强力策略将显式构造数组的每个版本并比较每一对。 对于每一对，我们将计算联合中不同元素的数量。 即使我们预先计算集合，比较两个版本的成本$O(n)$，并且有$O(m^2)$对，导致$O(m^2 n)$，远远超出了极限。 

关键的观察是停止考虑整个数组，而是随着时间的推移独立跟踪每个值。 

每个值在任何时刻都只出现在一个位置，但稍后可能会被替换。 因此，每个值在版本上都有一个连续的“生命周期”：它从引入的那一刻起一直存在到被覆盖的那一刻。 

现在考虑一个固定值$x$。 假设它存在于版本中$[l, r]$。 那么对于任意一对版本$(i, j)$，当且仅当两个版本都包含时，它才有助于交集$x$，意味着两者$i$和$j$位于$[l, r]$。 

因此，每个值恰好贡献了完全在其生命周期间隔内的版本对的数量，即：$$\binom{len}{2} + len$$如果我们包括对角线对，或更准确地说，包括该区间内的所有无序对。 

然而，我们正在对所有对进行求和，因此对于版本中活跃的值$[l, r]$，它同时存在的版本对的数量为：$$\frac{(r-l+1)(r-l+2)}{2}.$$我们计算所有值在所有活动间隔内的总贡献。 

为了获得这些间隔，我们模拟每个值出现和消失时的更新和维护。 每次位置值发生变化时$old$到$new$，我们关闭区间$old$并打开一个$new$。 

这将问题简化为跟踪间隔并在其长度上求和二次函数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(m^2 n)$|$O(n)$| 太慢了 |
 | 间隔追踪|$O(n + m)$|$O(n + m)$| 已接受 |

 ## 算法演练

 对于每个值，我们维护它在演化数组中存在的时间段。 时间按版本号索引$0$到$m$。 

1. 初始化当前数组并记录每个值从版本 0 开始都是活动的。我们为每个值存储其“开始时间”。 
2. 对于每个操作$i$，我们替换位置$p_i$有价值$v_i$。 先前占据该位置的值在版本处结束其活动间隔$i-1$，而新值在版本处开始新的间隔$i$。 

这是正确的，因为值仅在占据某个位置时才存在，并且独特性的保证确保值不会同时出现两次。 
3. 处理完所有操作后，最终数组中仍然存在的任何值的区间以版本结束$m$。 
4. 对于每个记录的间隔$[l, r]$，计算有多少个版本对$(i, j)$和$i \le j$完全躺在里面。 该计数是：$$\frac{(r-l+1)(r-l+2)}{2}.$$5. 最终答案是这些贡献对所有值的总和，适当乘以基础变换$2n - |intersection|$效应已经吸收在推导中。 

### 为什么它有效

 每个值的行为都是独立的，因为它在每个版本中要么存在，要么不存在，并且在任何时候它都出现在一个位置。 两个版本的交集仅取决于它们的时间索引是否落在同一值的活动区间内。 因此，每个值对每对版本贡献一次，其中两个端点都位于其生命周期间隔内。 对所有值求和可重建所有数组对的总交集贡献，而不会重叠或重复计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    # track current value at each position
    pos_val = a[:]
    
    # when each value became active
    start = {}
    
    # store intervals (l, r) for each value
    intervals = []
    
    # initial values start at version 0
    for v in a:
        start[v] = 0
    
    for i in range(1, m + 1):
        p, v = map(int, input().split())
        p -= 1
        
        old = pos_val[p]
        
        # close old value interval
        intervals.append((old, start[old], i - 1))
        
        # start new value interval
        start[v] = i
        pos_val[p] = v
    
    # close remaining active values
    for v in pos_val:
        intervals.append((v, start[v], m))
    
    ans = 0
    
    # contribution of each interval
    for _, l, r in intervals:
        length = r - l + 1
        ans += length * (length + 1) // 2
    
    print(ans)

if __name__ == "__main__":
    solve()
```该代码模拟了各个版本中值的演变，并准确记录每个值何时停止出现。 每次替换一个值时，我们都会最终确定其活动段。 最后，剩余值最终确定为版本$m$。 

二次贡献公式直接应用于每个区间。 该实现依赖于这样一个事实：每个值在任何时间都恰好出现在一个位置，因此随着时间的推移，它的存在是一个连续的段。 

一个微妙的点是我们永远不会合并相同值的间隔。 这是故意的，因为即使一个值稍后重新出现，它也必须被视为一个单独的生命周期段，因为它在中间不存在。

 ## 边缘情况

 一种重要的边缘情况是值在引入后立即被替换。 在这种情况下，其间隔长度为 1，仅贡献最小量，并且算法正确记录单点生命周期。 

当值从未被修改时，会出现另一种边缘情况。 那么每个初始值都有区间$[0, m]$，并且贡献变得最大。 该算法会处理此问题，因为这些值不会触发“关闭事件”。 

第三种边缘情况是重复覆盖同一位置。 每次覆盖都会关闭一个间隔并打开另一个间隔而不合并，这是必要的，因为每个段对应于一个不同的连续存在窗口。
