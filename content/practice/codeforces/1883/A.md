 ## 解决方案
 ## 问题理解

 我们被要求在设备上输入一个四位数的 PIN，其中的数字排列成一个圆圈`0`到`9`。 光标开始于`1`。 每一秒，我们都可以按下当前数字或将光标移动到相邻数字。 从一个数字移动到不直接相邻的另一个数字需要以顺时针或逆时针方向顺序移动通过圆圈。 

输入由多个测试用例组成，每个测试用例给出一个代表 PIN 的 4 位字符串。 输出是为每个测试用例输入 PIN 所需的最短秒数。 挑战在于，在圆形键盘上移动可以有快捷方式：从`0`到`9`只需 1 秒，而不是一路移动其他数字。 

约束条件很宽泛：最多`10^4`测试用例，每个都有一个 4 位 PIN 码。 这意味着我们的解决方案必须非常快，理想情况下每个测试用例的复杂度为 O(1)，因为操作总数可以达到 40,000，这是微不足道的。 边缘情况涉及跨越圆形边界的移动，例如，从`0`到`9`和重复的数字，例如`1111`，这应该最大限度地减少移动。 

粗心的方法可能会线性计算运动而不考虑圆形邻接。 例如，从`0`到`9`天真地可能会数到 9 步而不是 1 步。 

## 方法

 蛮力方法是模拟按压和移动的每一秒。 对于 PIN 中的每一位数字，我们可以将光标逐步向其移动一步，计算秒数，并在到达目标时按下。 这是正确的，但有点矫枉过正，因为任何两个数字之间的距离完全取决于它们在圆上的位置。 无需逐步模拟。 

关键的见解是圆形键盘上两个数字之间的距离是`min(abs(a-b), 10-abs(a-b))`。 这会测量顺时针和逆时针路径并选择较短的路径。 一旦我们知道了距离，按下数字总是需要 1 秒。 因此，对于长度为 4 的 PIN，总时间为每次按下 1 的总和加上连续数字之间的最小距离之和，从`1`。 

这将问题转化为每个测试用例的简单算术计算，消除了循环序列上的循环并使每个测试用例的解决方案为 O(1)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| 每个测试用例 O(4) | O(1) | O(1) | 对于较小的 n 是可以接受的，不必要的开销 |
 | 最佳圆距离计算 | 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化光标在数字处`1`。 
2. 对于每个数字`d`在 PIN 字符串中，计算到的最小圆距离`d`使用`min(abs(d - current), 10 - abs(d - current))`。 这表示顺时针或逆时针移动。 
3. 将计算出的距离添加到总时间中。 
4. 增加按数字 1 秒。 
5. 将光标移至`d`（更新当前位置）。 
6. 对 PIN 中的所有数字重复此操作。 
7. 返回测试用例的总秒数。 

为什么有效：圆形距离计算确保我们始终采用数字之间的最短路径。 增加 1 秒的按下时间以强制输入数字。 通过按顺序迭代 PIN，该算法可确保最小化总时间，而无需单独模拟每个动作。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    pin = input().strip()
    current = 1
    total = 0
    for ch in pin:
        target = int(ch)
        move = min(abs(target - current), 10 - abs(target - current))
        total += move + 1
        current = target
    print(total)
```该解决方案读取测试用例的数量，然后迭代每个 PIN。 对于每个数字，它计算圆形距离，按下时加 1，并更新光标。 使用`min(abs(...), 10-abs(...))`自动处理圆形运动，包括棘手的过渡，例如`0`到`9`。

 - 从 1 开始
 - 第一个数字“1”：移动= min(|1-1|,10-|1-1|)=0，按=1→总计=1，光标=1
 - 第二个数字“0”：移动= min(|0-1|,10-|0-1|)=1，按=1→总计=3，光标=0
 - 第三位数字'1'：移动= min(|1-0|,10-|1-0|)=1，按=1→总计=5，光标=1

 是的，总计 = 7 秒。 这符合预期。

 ## 边缘情况

 对于圆形边界，PIN`0`开始于`1`:

 - 从 1 开始 → 移动到 0：距离 = min(|0-1|, 10-1)=1
 - 按：+1 → 总计 2
 - 下一个数字 0 → 移动 0 步 → 按 → 总计 +1 = 3

 该算法正确地考虑了这个最小移动，而不是计算 9 步。 重复的数字，例如`1111`，导致按 4 次，没有移动，总共 4 次，这是正确的。
