 ## 解决方案
 ## 问题理解

 我们有 n 个朋友坐在一个聚会上，每个人都有一种独特的首选饮料。 Kaz 为每个朋友分配了一杯饮料，形成大小为 n 的排列。 有些朋友可能会立即收到正确的饮料，而另一些朋友则不会。 

有趣的部分是在这个初始任务之后发生的事情。 任何已经喝到正确饮料的人都会离开系统。 剩下的人仍然不高兴，把所有的饮料放回公共水池里。 然后，这些饮料会被随机洗牌并重新分配给剩下的人。 同样，现在碰巧收到正确饮料的任何人都会离开，并且重复该过程。 这一直持续到没有人留下为止。 

我们要求控制的数量就是这些洗牌轮的预期数量。 我们可以选择饮料的初始分配，并且我们希望最大限度地延长这种重复的随机“洗牌修复”过程所需的时间。 

关键输入只有n，即参与者的数量。 输出由两部分组成：一个表示最大可能预期轮数的实数，以及一个描述饮料最初如何分配的排列。 

约束 n ≤ 1000 意味着任何显式模拟随机性或考虑指数结构的解决方案立即不可行。 即使 O(n^2) 结构也可以，但是如果存在封闭式结构，任何涉及重复概率模拟或排列动态状态的操作都会太慢或在概念上是不必要的。 

当 n = 1 时，会出现微妙的边缘情况。如果唯一的人收到自己的饮料，他们会立即离开，并且该过程以零轮结束。 “总是至少有一轮”的天真假设在这里会失败。 

当 n = 2 时，结构变得信息丰富。 如果两个人都交换了，则该过程将在一轮洗牌中完成，因为下一次洗牌会立即解决这两个人。 这已经暗示初始排列的结构直接决定了在过程开始时有多少参与者是活跃的，并且这个初始状态主导了答案。 

## 方法

 蛮力视角首先修复排列并尝试计算所描述的随机过程下的预期轮数。 对于剩余 k 个参与者的任何状态，可以模拟将均匀随机排列应用于 k 个项目，计算出现了多少个固定点，删除它们，然后继续。 即使我们可以有效地计算一种排列的期望，评估所有 n！ 排列是不可能的。 

关键的简化来自于将初始排列的作用与过程的随机性分开。 在第一次分配之后，唯一重要的是有多少人最初是“错误的”，因为随后的每一轮都会通过对剩余的集合应用新的均匀随机排列来完全破坏结构。 谁错了并不重要，重要的是剩余集合的大小。 

一个关键的概率事实是，在 k 个元素的均匀随机排列中，当 k ≥ 1 时，固定点的预期数量始终恰好为 1。这意味着在至少有一个剩余参与者的每一轮中，离开该轮的预期人数为 1。 

因此，如果我们从系统中的 k 个人开始，每轮活跃参与者数量的预期每次减少为 1，直到系统变空。 这使得预期的轮数等于 k。

因此，整个问题归结为最大化 k，即最初错误的人数。 这是通过最小化初始排列中的固定点数来实现的。 最好的可能排列是混乱，其中没有索引 i 满足 p[i] = i，因此 k = n。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 指数| O(n) | 太慢了|
 | 构造混乱| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 如果 n 等于 1，则输出仅包含 1 的排列，并将期望值设置为 0。该过程从空开始，因为唯一的参与者已经是正确的，因此不会发生洗牌。 
2. 如果n大于1，构造任意无不动点的排列。 一个简单的结构是将每个索引移动一个位置，将 i 发送到 i + 1，将 n 发送到 1。这保证了每个朋友最初都喝错了。 
3. 输出期望的轮数为n。 这是因为所有 n 个参与者都开始进行交换过程，并且每轮移除的参与者的预期数量始终为 1。 
4. 输出构建的排列。 

重要的设计选择是确保最初的零固定点。 任何固定点都会立即减少初始活跃集并严格减少预期轮数，因为每个固定点都是根本不进入交换过程的参与者。 

### 为什么它有效

 令 k 为最初没有得到正确饮料的人数。 这些正是进入交换过程的参与者。 在每一轮中，无论历史如何，剩余的集合都是随机统一重新洗牌的，因此只要至少有一个人留下来，则一轮中离开的预期人数始终为 1。 根据期望的线性度，总的期望轮数恰好是 k。 由于 k 不能超过 n，因此当 k = n 时达到最大值，这恰好发生在排列是混乱的情况下。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())

if n == 1:
    print("0.0")
    print(1)
    exit()

# build derangement: shift by 1
p = list(range(2, n + 1)) + [1]

print(float(n))
print(*p)
```第一步处理无法进行交换过程的退化情况。 对于所有较大的 n，该构造使用简单的循环移位保证无固定点的排列。 这已经足够了，因为任何混乱都是最佳的。 

打印的值只是简单地转换为浮点格式。 除了确保最大程度的初始参与之外，不依赖于结构。 

这里的一个常见错误是尝试显式模拟过程或计算概率。 关键是该过程每轮都会“重置随机性”，使系统仅依赖于当前集合的大小，而不依赖于历史记录。 

## 工作示例

 考虑 n = 3 和排列 [2, 3, 1]。 

| 圆形| 活动集大小 | 预计搬迁| 剩余|
 | --- | --- | --- | --- |
 | 0 | 3 | - | 3 |
 | 1 | 3 | 1 | 2 |
 | 2 | 2 | 1 | 1 |
 | 3 | 1 | 1 | 0 |

 该跟踪表明，每一轮都会移除一个预期的参与者，直到系统清空。 初始大小直接决定了预期的轮数。 

对于 n = 1 且排列 [1]，系统开始为空：

 | 圆形| 活动集大小 | 预计搬迁| 剩余|
 | --- | --- | --- | --- |
 | 0 | 0 | - | 0 |

 这确认没有发生洗牌并且预期的轮数为零。

 ## 边缘情况

 对于 n = 1，算法输出一个简单的排列并正确返回 0.0，因为没有参与者进入交换过程。 构建的逻辑完全绕过了混乱步骤。 

对于 n = 2，排列 [2, 1] 确保两个参与者最初都是错误的。 经过一次洗牌后，两者都按预期同时解决，从而为两个参与者提供了预期的回合数。 

对于较大的 n，循环移位保证没有固定点，这意味着所有参与者从一开始就为该过程做出贡献。 预期的轮数与 n 成线性比例，因为该过程在预期中每轮仅删除一个参与者。
