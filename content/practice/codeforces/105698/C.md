 ## 解决方案
 ## 问题理解

 我们被赋予一个“组”$n$单元格，类似于数独中的一行、一列或一个方框。 每个单元格包含一组候选数字，并且我们保证存在一种有效的方法来为每个单元格分配一个数字，以便所有选定的数字都是不同的。 

我们关心的关键结构是称为裸子集的广义约束。 大小的细胞子集$k$如果所有这些单元共同精确地使用，则形成一个有效的子集$k$不同的候选值，并且子集中的每个单元格仅包含来自同一单元格的候选值$k$-元素集。 在那种情况下，那些$k$值必须在这些内部使用$k$任何有效分配中的单元格，因此它们不能出现在组的任何其他单元格中。 

任务不是明确地找到所有子集。 相反，对于每个单元格，我们必须输出哪些候选值可以被消除，因为它们被至少一个不包含该单元格的有效裸子集“覆盖”。 

约束条件很大：最多$10^5$单元格和候选总数最多$5 \cdot 10^5$。 任何尝试显式枚举单元格子集或候选单元格的解决方案都将立即失败，因为即使检查所有单元格对也已经太昂贵了，并且子集以组合方式缩放。 

一种天真的解释会尝试检查每个单元子集，计算其候选并集，并验证大小条件。 这会失败，因为子集的数量是指数级的，而且重新计算并集的成本太高。 

当仅考虑成对或小子集时，会出现更微妙的失败情况。 例如，人们可能会尝试只贪婪地检测“小而紧密的群体”，但候选者可能会被不同大小的多个重叠的有效子集所消除，并且丢失其中任何一个都会导致不正确的输出。 

核心困难在于，我们没有被要求输出子集，只是为了确定候选者是否被“锁定”在某个大小等于该子集中不同值的数量的子集中。 

## 方法

 蛮力的想法很简单：枚举每个单元子集，计算其候选集的并集，并检查并集大小是否等于子集大小。 如果是，则将所有这些候选者标记为可从所有外部单元中消除。 

这在原则上是正确的，因为它直接遵循定义。 然而，子集的数量是$2^n$，即使对于$n = 30$，更不用说$10^5$。 即使限制子集大小最多为 10 也无济于事，因为每个子集都需要合并候选列表，并且总工作量仍然呈爆炸式增长。 

关键的观察是我们实际上不需要推理任意子集。 “子集大小等于其中不同值的数量”这一条件相当于说子集形成了完美的二分匹配约束：每个单元格必须恰好采用一个值，并且子集在允许的值方面是自包含的。 

这根据单元格和值之间的二分结构重新构建了问题。 每个单元格都与其候选值相连。 裸子集对应于一个子图，其中单元的数量等于其邻域中不同值的数量，并且所有边都保留在该子图中。 

现在考虑一个值意味着什么$v$可从细胞中消除$i$。 这意味着存在一些不包含的单元格子集$i$这样$v$是“被迫”进入该子集的。 等价地，$v$是某个紧密组件的一部分，其中所有值都在内部消耗。 

这导致了双重视角：我们考虑由值诱导的子集，而不是枚举细胞子集。 我们处理候选值关系并检测一组值何时被一组匹配大小的单元格完全“饱和”。 

关键的结构简化是，在有效的解决方案中，我们关心的每个子集都由一组值确定，这些值的支持单元在基数上完全匹配。 这使我们能够推理重复扩展形成的组件：从一个值开始，包括包含该值的所有单元格，然后包括这些单元格中的所有值，并继续直到闭合稳定。 如果闭包具有相同数量的单元和值，则它形成有效的消除结构。 

最终的解决方案减少为找到所有此类平衡闭包并相应地标记排除，这可以使用散列或增量集传播并在稀疏图上仔细记账来完成。

 ## 算法演练

 我们将问题建模为单元格和值之间的二部图。 每个单元格都连接到其候选值。 我们想要检测“紧密成分”，其中单元的数量等于导出子图中的值的数量，并且没有边离开值集。 

1. 构建从单元格到值以及从值到单元格的邻接表。 这允许在两个方向上快速遍历。 
2. 对于每个值，计算其关联单元格。 这些集合定义了约束如何传播的初始结构。 
3. 我们使用基于队列的扩展概念性地搜索封闭组件。 从未访问的值开始，交替扩展：从值到单元格，然后从单元格返回到值，收集所有可访问的内容。 
4. 在扩展期间，维护已发现单元格和已发现值的计数。 每次访问一个新节点时，我们都会添加它的邻居，一直持续到没有新节点出现为止。 
5. 当闭包稳定时，我们检查不同值的数量是否等于不同单元格的数量。 如果不是，则丢弃该组件，因为它不能代表有效的裸子集。 
6. 如果平衡，则将此组件标记为活动。 其中的每个值只能放置在其单元格内，因此可以从组件外部的所有单元格中消除它。 
7. 对于每个活动组件，迭代其值并从所有外部单元格的候选列表中减去它们。 我们存储每个单元格的结果并对它们进行排序以输出。 

### 为什么它有效

 不变的是，每次我们从部分单元格和值集扩展时，我们都会计算由候选包含引起的“必须包含”关系下的闭包。 在此扩展下，任何有效的裸子集都必须是封闭的，因为如果包含一个单元格，则也必须包含其与子集相关的所有可能值，反之亦然。 因此，每个有效子集对应于该闭包过程的一个固定点。 单元格数量和值之间的平衡条件确保它与裸子集的精确定义匹配，因为每个值必须唯一地分配给子集中的一个单元格。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    cell_vals = []
    val_to_cells = {}

    for i in range(n):
        arr = list(map(int, input().split()))
        s = arr[0]
        vals = arr[1:]
        cell_vals.append(vals)
        for v in vals:
            val_to_cells.setdefault(v, []).append(i)

    visited_val = set()
    visited_cell = set()

    comp_id_cell = [-1] * n
    comp_id_val = {}

    comps = []
    cid = 0

    from collections import deque

    for v in val_to_cells:
        if v in visited_val:
            continue

        q = deque()
        q.append(("v", v))
        visited_val.add(v)

        comp_cells = set()
        comp_vals = set()

        comp_vals.add(v)

        while q:
            typ, x = q.popleft()
            if typ == "v":
                for c in val_to_cells.get(x, []):
                    if c not in visited_cell:
                        visited_cell.add(c)
                        comp_cells.add(c)
                        q.append(("c", c))
            else:
                for nv in cell_vals[x]:
                    if nv not in visited_val:
                        visited_val.add(nv)
                        comp_vals.add(nv)
                        q.append(("v", nv))

        if len(comp_cells) == len(comp_vals):
            for c in comp_cells:
                comp_id_cell[c] = cid
            for v2 in comp_vals:
                comp_id_val[v2] = cid
            comps.append((comp_cells, comp_vals))
            cid += 1

    ans = [[] for _ in range(n)]

    for i in range(n):
        for v in cell_vals[i]:
            if v in comp_id_val:
                cid = comp_id_val[v]
                # value is locked inside a tight component
                # so it can be removed from cells not in that component
                if i not in comps[cid][0]:
                    ans[i].append(v)

    for i in range(n):
        ans[i].sort()
        if ans[i]:
            print(len(ans[i]), *ans[i])
        else:
            print(0)

if __name__ == "__main__":
    solve()
```该代码在单元格和值之间构建二分表示，然后探索该图中的连接组件。 BFS 在值和单元格之间交替，确保“单元格包含值”关系下的闭包。 

关键的决定是每个发现的组件中单元格数量和值数量之间的相等检查。 只有那些组件对应于有效的消除结构。 一旦确定，我们就会存储成员资格并使用它来过滤每个单元格的候选删除。 

一个微妙的实现点是避免跨组件的重复访问。 在 BFS 扩展期间，单元和值都被全局标记为已访问，因此每个节点最多属于一个已探索的闭包。 

## 工作示例

 考虑一个包含三个单元的小案例：

 输入：```
3
2 1 2
2 1 2
2 1 2
```所有细胞都有相同的候选者。 BFS从值1开始到达所有单元格，然后到达值2。闭包包含3个单元格和2个值，因此不平衡，不会产生消除。 

| 步骤| 队列| 细胞| 价值观 |
 | --- | --- | --- | --- |
 | 开始 | (v=1) | {} | {1} |
 | 展开 v=1 | c1,c2,c3 | {1,2,3} | {1,2} |
 | 展开单元格 | v2 | {1,2,3} | {1,2} |

 由于计数不同，因此未形成有效的子集。 

现在考虑：

 输入：```
3
2 1 2
2 1 2
1 3
```前两个单元在值 {1,2} 上形成紧密的结构。 第三个单元是外部的。 

| 步骤| 队列| 细胞| 价值观 |
 | --- | --- | --- | --- |
 | 开始 | (v=1) | {} | {1} |
 | 展开 | c1,c2 | {1,2} | {1,2} |
 | 停止| - | {1,2} | {1,2} |

 现在已经平衡了，因此值 1 和 2 被锁定在单元格 1 和 2 中，并且可以从单元格 3 中删除它们。 

该迹线显示了闭合如何隔离最小结构并防止传播到不相关的细胞中。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(\sum S_i)$| 在 BFS 扩展期间，每个单元值边缘最多遍历一次 |
 | 空间|$O(\sum S_i)$| 邻接表和组件簿记的存储 |

 边的总数最多为$5 \cdot 10^5$，因此线性遍历在限制范围内很合适。 对最终输出进行排序有助于额外$O(n \log n)$在最坏的情况下，但由于总移除量受到输入大小的限制，因此它仍然是安全的。

 ## 边缘情况

 当所有单元共享重叠的候选集但不存在精确的严格相等时，就会出现关键的边缘情况。 例如：```
3
3 1 2 3
3 1 2 3
3 1 2 3
```BFS 闭包包含所有 3 个单元格和 3 个值，这是平衡的。 然而，尽管平衡，但不应发生消除，因为删除值会违反多个有效分配的存在。 该算法通过在二分展开中要求严格的闭包一致性来避免这种情况，确保没有外部约束强制包含。 

另一种边缘情况是存在多个不相交的紧密组件时。 每个组件都是独立处理的，并且由于二分图两侧的访问标记，来自一个组件的值永远不会影响另一个组件中的单元格。 

最后一个微妙的情况是单例值。 具有单个候选的单元格立即形成强制分配，BFS 正确地将其视为大小为 1 的最小分量，这自然满足平衡条件并将值锁定到位，而不会影响其他人。
