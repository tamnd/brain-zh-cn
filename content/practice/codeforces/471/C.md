 ## 解决方案
 ## 问题理解

 纸牌屋是用地板建造的。 如果地板包含`k`房间，那么每个房间使用两张学习卡，所以房间本身消耗`2k`牌。 相邻房间之间和最外面的房间上方有一个由水平卡片制成的天花板。 一排`k`房间需求`k - 1`相邻房间之间共享天花板卡，并且每个房间位置上方多一张天花板卡，这使得总共`k - 1 + 1 = k`水平卡片。 

所以一个地板`k`房间用途：$$2k + (k-1)=3k-1$$牌。 

当我们向上穿过房子时，房间的数量必须严格减少。 如果地板包含$$a_1 > a_2 > \dots > a_h \ge 1$$房间，那么卡片总数为$$\sum_{i=1}^{h}(3a_i-1) = 3\sum a_i - h.$$我们准确地给出了`n`卡片并必须数出有多少种不同的高度`h`是可能的。 如果存在严格递减的房间数正序且其卡消费总额恰好为，则高度有效`n`。 

约束是有趣的部分。`n`可以大到`10^12`。 任何枚举分区或探索地板尺寸组合的方法都是没有希望的。 甚至`O(n)`太大了。 我们需要更接近对数或平方根的复杂度。 

当根本没有有效的房子时，就会出现一个微妙的情况。 例如：```
6
```最小的一层房屋用途`2`卡，最小的二层房屋用途`7`卡，并且没有有效的配置准确消耗`6`。 答案是`0`。 

另一个容易犯的错误是忘记了严格的减少条件。 考虑：```
13
```使用房间数`(2,2)`会消耗`10`卡，但这是非法的，因为楼层并没有严格递减。 只允许严格递减的序列。 

错误的第三个来源是分别计算不同的房间分布。 该问题要求的是可能的高度的数量，而不是房屋的数量。 如果多个不同的地板配置具有相同的高度，则它们仅贡献一次。 

## 方法

 直接的暴力解释是生成所有严格递减的正整数序列，计算它们的卡使用情况，并检查它是否等于`n`。 这是正确的，因为每个合法宫位都恰好对应一个这样的序列。 不幸的是，递减序列的数量呈爆炸式增长。 即使对于中等值`n`，搜索空间类似于整数分区的数量，这远远超出了当`n`达到`10^12`。 

关键的观察结果来自重写卡片公式：$$n = 3\sum a_i - h.$$重新排列给出$$\sum a_i = \frac{n+h}{3}.$$对于固定高度`h`，问题就变成：

 我们可以写吗$$S=\frac{n+h}{3}$$作为总和`h`不同的正整数？ 

这是一个经典的数论问题。 

最小可能的总和`h`不同的正整数由下式获得$$1+2+\cdots+h = \frac{h(h+1)}2.$$一旦我们有了这样一个集合，将最大元素增加任何非负数就可以保持独特性。 因此，每个整数和至少$$\frac{h(h+1)}2$$是可以实现的。 

那么一个高度`h`当两个条件成立时恰好有效：$$n+h \equiv 0 \pmod 3$$和$$\frac{n+h}{3}\ge \frac{h(h+1)}2.$$第二个不等式变为$$h^2+h \le \frac{2(n+h)}3.$$化简后：$$3h^2+h-2n \le 0.$$这立即给出了大致的上限$$h \le \sqrt{\frac{2n}{3}},$$即使对于`n = 10^{12}`。 我们可以简单地测试达到该界限的所有可能的高度。

 ## 算法演练

 1. 迭代所有可能的高度`h`开始于`1`。 
2. 停止时`3h² + h > 2n`。 对于更大的高度，所需的最小卡片数量已经超过`n`，因此不再有效的高度。 
3. 检查是否`n + h`可以整除`3`。 如果不是，那么`S = (n+h)/3`不是整数并且没有高度的房子`h`存在。 
4. 如果整除成立，验证最小和条件$$\frac{n+h}{3} \ge \frac{h(h+1)}2.$$这与上面的推导是等价的。 
5. 如果满足条件，则增加答案。 
6. 测试完所有可行高度后，输出计数。 

### 为什么它有效

 适合任何身高`h`，每个合法宫位都对应一个严格递减序列`h`房间数为正。 总卡公式将问题转化为询问是否`(n+h)/3`可以表示为总和`h`不同的正整数。 

总和`h`当至少为 时，不同的正整数恰好存在`1+2+\cdots+h`。 每个更大的值都可以通过增加最大元素同时保持独特性来获得。 因此，整除条件和最小和条件都是充分必要的。 该算法精确检查每个可行高度的这些条件，因此每个有效高度都会被计算一次，并且每个无效高度都会被拒绝。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    ans = 0
    h = 1

    while 3 * h * h + h <= 2 * n:
        if (n + h) % 3 == 0:
            s = (n + h) // 3
            if s >= h * (h + 1) // 2:
                ans += 1
        h += 1

    print(ans)

solve()
```变量`h`代表当前测试的高度。 

循环条件直接来自不等式$$3h^2+h-2n \le 0.$$一旦失败，即使是该高度的最小可能的房子也需要比可用的更多的牌，所以更大的高度也不起作用。 

在计算之前执行整除性检查`s`。 没有它，整数除法将默默地接受不可能的情况。 

对比`h(h+1)/2`将表示的存在编码为总和`h`不同的正整数。 由于Python整数具有任意精度，因此即使在`n = 10^{12}`。

 ## 边缘情况

 考虑输入：```
1
```循环条件`3h²+h≤2n`已经失败了`h=1`因为`4>2`。 没有检查身高，答案仍然存在`0`。 这正确地反映了即使是一个房间也需要两张卡。 

考虑：```
6
```为了`h=1`,`n+h=7`，不能被三整除。 为了`h=2`,`n+h=8`，也不能被三整除。 不存在有效高度。 仅检查最小卡不等式的粗心实现会错误地接受某个高度。 

考虑：```
7
```为了`h=2`,$$S=\frac{7+2}{3}=3.$$两个不同正整数的最小和也是`3`，即`1+2`。 该条件在边界处完全满足，产生一个有效高度。 这个案例发现了一个微小的错误，其中`>`被用来代替`>=`。 

最后，考虑：```
13
```为了`h=2`，我们得到`S=5`，大于最小总和`3`。 代表性`1+4`存在，提供有效的两层楼房屋。 无论有多少房间分布产生该高度，该算法都会对高度进行一次计数，以满足问题要求。
