 ## 解决方案
 ## 问题理解

 问题要求我们构造一个长度的数组`n`使其元素按位或与目标值`x`同时最大化数组的 MEX。 MEX（或最小排除值）是数组中不存在的最小非负整数。 每个测试用例都给我们`n`和`x`，并且我们需要生成满足 OR 要求并具有尽可能高的 MEX 的数组。 

限制因素很重要：`n`最多可以达到 200,000，所有测试用例的总和以 200,000 为界。 这告诉我们任何迭代所有可能的子集或执行的解决方案`O(n^2)`操作是不可行的。 相反，我们需要一个`O(n)`每个测试用例的解决方案。 的价值`x`最多可达近十亿，因此单个数组元素必须小于`2^30`。 

边缘情况是`n = 1`。 这里，数组必须是`[x]`因为只存在一个元素。 在这种情况下，MEX 为 0，如果`x > 0`，或 1 如果`x = 0`。 另一个棘手的情况是当`x`很小并且`n`很大。 天真地填写数字`0`通过`n-1`可能超过`x`当与之前的数字进行“或”运算时，需要小心。 例如，`n = 7`,`x = 3`不能有`[0,1,2,3,4,5,6]`因为`OR`所有元素的总和将超过`3`。 

不明显的部分是在尊重 OR 的同时最大化 MEX。 为了最大化 MEX，我们需要从 0 开始的连续数字，但每个数字必须被“允许”`x`- 意味着它的设置位必须是设置位的子集`x`。 

## 方法

 暴力方法会枚举每一个组合`n`数字小于`2^30`其 OR 等于`x`，计算每个的 MEX，并选择最大值。 即使是为了`n = 20`，组合的数量是天文数字，所以暴力破解是不可能的。 

关键的观察是数组中包含的任何数字都不能设置在`x`。 这意味着我们可以自由地使用其位是以下子集的数字`x`来形成数组。 我们还注意到，包括数字`0`通过`k-1`连续保证 MEX 至少`k`。 因此，策略是选择尽可能多的从 0 开始的连续数字，跳过需要外部位的数字`x`。 一旦我们填满`n-1`这样，最后一个元素可以是实现所需 OR 的任何剩余元素`x`。 

我们将问题简化为两步：生成从 0 开始的数字，其位是`x`，然后附加一个最终数字以确保 OR 准确无误`x`。 这种贪婪的建设性方法运行在`O(n)`并且在给定的约束下是足够的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O((2^30 选择 n)) | O(n) | 太慢了 |
 | 贪婪的建设性| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.初始化一个空数组`a`。 
2. 从`i = 0`并反复检查是否`i`有任何位之外`x`。 如果所有位都在`i`也在`x`， 添加`i`到`a`。 停止时`len(a) = n-1`。 这可确保所有包含的数字不会违反 OR 约束。 
3. 计算数组的当前 OR。 数组的最后一个元素必须是`x`对当前 OR 进行异或以确保总 OR 等于`x`。 
4. 将此最后一个元素附加到`a`。 如果最终元素与现有数字重复，也没关系，因为 MEX 是由从 0 开始的连续数字决定的，而我们已经将其最大化。 
5. 输出数组。 

为什么它有效：贪心步骤保证从 0 开始的最大可能的连续数字块，所有数字都允许`x`，包含在内。 最终的 XOR 保证完全满足 OR 要求。 不需要额外的操作，这会生成一个具有最大化 MEX 的有效数组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = []
        i = 0
        while len(a) < n - 1:
            if (i | x) == x:
                a.append(i)
            i += 1
        current_or = 0
        for num in a:
            current_or |= num
        a.append(x ^ current_or)
        print(' '.join(map(str, a)))
```该解决方案快速读取输入，贪婪地构建数组，并使用 XOR 附加最终数字以满足 OR。 请注意仅包含其位是以下子集的数字`x`。 循环停止条件`len(a) < n-1`确保最终异或元素的空间。

 ## 边缘情况

 当`n = 1`，填充循环`n-1`元素被跳过，异或最终元素变为`x`。 为了`x = 0`，算法填充零并且最后一个元素也为零。 为了`x`小于`n`，算法自动跳过位在外面的数字`x`并贪婪地填充数组，确保最大 MEX 且不超过 OR。 每个场景自然由循环条件和最终的异或计算来处理。
