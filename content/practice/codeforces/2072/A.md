 ## 解决方案
 ## 问题理解

 我们从一系列`n`零。 一步操作中，我们可以选择任意位置并用范围内的任意整数覆盖它`[-p, p]`。 执行一定次数的此类覆盖后，我们希望数组的总和恰好变为`k`，我们希望用尽可能少的动作来做到这一点。 每一步仅影响一个位置，并且完全替换该位置的前一个值。 

因此，真正的决定不是关于位置，而是关于我们最多可以使用多少总和“注入”到数组中`n`作业，每个作业之间贡献一个值`-p`和`p`。 

限制很小：`n ≤ 50`,`|k| ≤ 2500`， 和`p ≤ 50`。 这意味着即使直接案例分析或贪心公式也足够了。 任何类似于 DP 超过州的做法都是不必要的，甚至对每个职位可能的分配进行暴力处理在理论上也足够有限，但在实践中却太过分了。 

一个常见的失败案例是忘记我们可以多次覆盖同一个索引。 由于每个索引只有最终值很重要，所以重要的是我们使用了多少个索引，而不是我们接触它们的频率。 

另一个微妙的情况是当`k = 0`。 正确的答案始终是零运算，因为数组的总和已经为零，无论`p`。 

## 方法

 蛮力的想法会尝试所有方法将值分配给最多`n`位置并检查哪些组合总和为`k`。 这很快就会爆炸，因为每个位置都有`2p + 1`选择，导致`(2p + 1)^n`可能性，即使对于`n = 50`。 

关键的观察是每个操作对总和的贡献是独立的。 后`x`操作，我们能做的最好的事情是`x * p`，因为每个作业最多可以贡献`p`或者`-p`。 所以确切之后可达到的总和`x`运算形成区间`[-x p, x p]`。 因为我们想要的是`k`，唯一的问题是是否`k`就在这个范围内，最小的这个范围是多少`x`是。 

这将问题简化为寻找最小值`x`这样`x * p ≥ |k|`，同时还保证`x ≤ n`因为我们只有`n`位置进行修改。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(1) | O(1) | 太慢了|
 | 贪婪绑定检查 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，请阅读`n`,`k`， 和`p`。 我们只关心绝对值`k`因为我们可以对称地使用负赋值。 
2.如果`k`为零，返回`0`立即执行，因为不需要任何操作并且初始数组已经满足条件。 
3. 计算`need = |k|`。 这代表我们必须使用操作构建多少总量。 
4. 每个操作最多贡献`p`到总震级。 所以所需的最少操作次数为`ceil(need / p)`。 
5. 如果这个数字大于`n`，那么即使每个元素修改一次也不足以达到所需的总和，所以答案是`-1`。 
6. 否则，输出计算值。 

为什么有效：每个操作对总和都有独立贡献，我们可以自由分配正值或负值，最多可达`p`。 唯一的限制因素是总容量，它与操作数量成线性关系。 由于只要容量允许，我们总是可以选择与所需总和完全匹配的值，因此上限界限既是必要的也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, p = map(int, input().split())

        if k == 0:
            print(0)
            continue

        need = abs(k)

        # minimum operations needed if each contributes at most p
        ops = (need + p - 1) // p

        if ops > n:
            print(-1)
        else:
            print(ops)

if __name__ == "__main__":
    solve()
```实现直接遵循派生界限。 吊顶划分`(need + p - 1) // p`避免浮点运算并确保所有整数情况的正确性。 支票`ops > n`强制执行我们不能执行更多操作的约束`n`独立作业。

## 测试用例```python
import sys, io

def solve_io(data):
    sys.stdin = io.StringIO(data)
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, k, p = map(int, input().split())
        if k == 0:
            out.append("0")
            continue
        need = abs(k)
        ops = (need + p - 1) // p
        out.append(str(ops if ops <= n else -1))

 ## 边缘情况

 当`k = 0`，算法立即返回零，而不考虑`p`，因为不需要修改。 什么时候`p`相对于`k`，该公式分解为一个运算，因为单个赋值可以吸收整个总和。 什么时候`p = 1`，操作数正好变为`|k|`，可行性完全取决于是否`|k| ≤ n`。 上限除法确保在所有这些情况下都不会出现差一错误，因为它可以正确处理可整除和不可整除的量值。
