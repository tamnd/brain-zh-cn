 ## 解决方案
 ## 问题理解

 我们从一个第一行包含单个值的三角形开始`k`。 

后面的每一行都是从前一行构建的。 两个边框元素是从上面的行复制的，而每个内部元素都成为其上面两个相邻元素的异或。 

如果我们将三角形表示为`T`，然后行`n`包含`n`数字。 任务是输出整个`n`-扔。 

乍一看，这看起来与帕斯卡三角形非常相似。 唯一的区别是加法已被异或代替。 这种相似性是解决问题的关键。 

约束足够大，显式构造整个三角形是不可能的。 单个测试用例可能会要求`n = 10^6`。 将所有行构建到该级别大约需要$$1+2+\cdots+n = O(n^2)$$操作，这变成了关于$5 \cdot 10^{11}$更新时间$n=10^6$。 那是完全遥不可及的。 

所有请求的行长度之和最多为$10^6$。 这告诉我们一些重要的事情：$O(n)$每个测试用例的解决方案是可以接受的，因为所有测试用例的总工作量保持线性。 

一些边缘情况很容易被忽略。 

考虑`n = 1`。 

输入：```
1 52
```输出：```
52
```没有复发可以申请。 答案很简单，就是第一行。 

另一个微妙的情况是当请求的行索引是二加一的幂时。 

例如：```
n = 9, k = 1
```答案是：```
1 0 0 0 0 0 0 0 1
```在小行中搜索数字模式的天真尝试常常会失败。 正确的结构来自二项式系数的奇偶性，而不是来自值本身。 

最后一个陷阱是假设答案取决于`k`。 整行仅由某个系数是奇数还是偶数来确定。 每个非零条目恰好是`k`，从来没有它的一些变形版本。 

## 方法

 最直接的解决办法就是模拟重现。 

开始于`[k]`，重复构建下一行。 每个内部位置都是前一行中两个相邻值的异或，并且复制边框。 

这种方法是正确的，因为它完全遵循定义。 不幸的是，它需要构造所有行`1`通过`n`。 总工作量为$$1+2+\cdots+n = O(n^2).$$为了`n = 10^6`，这太慢了。 

The recurrence strongly resembles Pascal's triangle. 在帕斯卡三角形中，行处的条目`r`和列`c`等于$$\binom{r}{c}.$$用 XOR 代替加法意味着我们有效地对模 2 进行运算。由于 XOR 是在 GF(2) 域上进行加法，所以行中的每个位置`n`等于$$k \cdot \left(\binom{n-1}{j-1}\bmod 2\right).$$如果二项式系数为奇数，则值为`k`。 如果是偶数，则值为`0`。 

现在问题简化为确定是否$$\binom{n-1}{j-1}$$很奇怪。 

卢卡斯定理的一个经典推论指出：$$\binom{a}{b}$$当每个位都设置为奇数时`b`也设置在`a`。 按位形式：$$(b \,\&\, \sim a)=0.$$等价地，$$(a \,\&\, b)=b.$$让$$m=n-1.$$对于职位`j`， 定义$$r=j-1.$$那么条目是`k`如果`(r & m) == r`， 否则`0`。 

现在，每个元素都可以在恒定时间内独立生成，从而给出整体线性解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |

 |---|------|---|

 | 蛮力 | O(n²) | O(n) | 太慢了 |

 | 最佳 | O(n) | O(1) 不包括输出 | 已接受 |

 ## 算法演练

 1. 阅读`n`和`k`。 
2. 计算`m = n - 1`。 

行中的每个系数`n`对应于行的二项式系数`m`帕斯卡三角形。 
3. 对于每个位置`j`从`0`到`n-1`，检查是否`(j & m) == j`。 

这正是条件`C(m, j)`很奇怪。 
4. 如果条件为真，则追加`k`到答案。 

奇数系数意味着一个副本`k`XOR 累积后仍然存在。 
5. 否则附加`0`。 

偶数系数在 XOR 下被抵消。 
6. 输出生成的行。 

### 为什么它有效

 三角形的每个元素都是通过重复应用 XOR（即模 2 的加法）形成的。因此，递推式与通过 GF(2) 计算的帕斯卡三角形相同。 

原值的系数`k`在位置`j`在行中`n`正是`C(n-1, j)`。 由于 XOR 只关心奇偶性，因此奇数系数会贡献一份副本`k`，而偶数系数则无任何贡献。 

卢卡斯定理告诉我们`C(m, j)`恰好是奇数，当每个设置位`j`也存在于`m`。 按位测试`(j & m) == j`准确检查该条件。 因此，每个位置都被正确分类为`k`或者`0`，证明算法的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, k = map(int, input().split())
        m = n - 1

        row = []
        for r in range(n):
            if (r & m) == r:
                row.append(str(k))
            else:
                row.append("0")

        out.append(" ".join(row))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```实现直接遵循数学特征。 

变量`m = n - 1`对应于帕斯卡三角形行索引。 对于每个职位`r`，这代表`j - 1`在基于一的索引中，我们测试是否所有位`r`都包含在里面`m`。 

如果`(r & m) == r`，对应的二项式系数为奇数，所以值为`k`。 否则就是`0`。 

没有构造三角形。 该代码直接在线性时间内生成请求的行。 

最常见的实施错误是混合从一开始的索引和从零开始的索引。 奇偶校验测试必须应用于`r = j - 1`，这正是循环变量所代表的内容。 

另一个常见的错误是尝试显式计算二项式系数。 他们的价值早已变得巨大`n`达到极限，奇偶校验测试避免了所有此类计算。

 ## 边缘情况

 ### 边缘情况 1：单元素行

 输入：```
1
1 52
```该算法计算`m = 0`。 

为了`r = 0`：```
(0 & 0) == 0
```为 true，因此输出为：```
52
```无需特殊处理。 

### 边缘情况 2：两行边界的幂

 输入：```
1
9 1
```这里`m = 8`, 二进制`1000`。 

仅有的`r = 0`和`r = 8`满足`(r & m) == r`。 

该算法输出：```
1 0 0 0 0 0 0 0 1
```这捕获了错误地假设帕斯卡三角形行保持密集的实现。 

### 边缘情况 3：每个系数均为奇数

 输入：```
1
4 9
```这里`m = 3`, 二进制`11`。 

每一个`r`在`{0,1,2,3}`仅使用已存在的位`m`，所以所有位置都满足条件。 

输出：```
9 9 9 9
```这验证了该算法处理在 XOR 下没有发生取消的行。
