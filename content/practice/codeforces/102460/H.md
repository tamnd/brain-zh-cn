 ## 解决方案
 ## 问题理解

 对于每个正整数 (n)，我们需要选择一个正整数 (b) 和一个整数 (a)，使得

 [
 \frac{1}{n}=\frac{1}{a\oplus b}+\frac{1}{b},
 ]

 其中 (\oplus) 是按位异或。 在所有有效选择中，我们想要尽可能大的 (a)。 

输入最多包含 (n) 的 20 个独立值，其中 (n\le 10^7)。 答案可能比 (n) 大得多，大约达到 (n^2)，因此实现必须使用能够保存 (10^{14}) 左右值的整数类型。 Python 整数具有任意精度，因此不存在溢出问题。 

数值界限 (10^7) 也是反对枚举的强烈信号。 对于一种情况，具有 (O(n)) 工作量的循环已达到 (10^7) 次迭代，而对 (b) 的所有潜在相关值的直接搜索达到 (O(n^2))，这可能约为 (10^{14}) 次迭代。 只有 20 个测试用例，就可以达到大约 (2\cdot10^{15}) 次迭代，远远超出了时间限制。 该解决方案需要将问题减少到每个测试用例的算术和按位运算的恒定数量。 

第一个边缘情况是 (n=1)。 方程变为

 [
 1=\frac1{a\o+b}+\frac1b。 
]

 两个分母都必须大于 1，并且经过下面的代数变换后唯一可能的对是 (b=2) 和 (a\oplus b=2)。 因此(a=0)。 假设答案必须是肯定的粗心实现将在输入上失败`1`，其正确输出是`0`。 

第二个边缘情况是 (n=2)。 最优结构给出 (b=3), (a\oplus b=6)，因此

 [
 a=6\oplus3=5。 
]

 正确的输出是`5`。 如果搜索意外地在 (n+2) 处开始 (b)，而不是允许 (b=n+1)，则会错过最佳值。 

官方样本是（n=6,7,10），生产（45,48,101），（n=1,2,7777777），生产（0,5,60493819864864）。 

## 方法

 一种直接的方法是枚举 (b) 的可能值。 让

 [
 c=a\o加b。 
]

 该方程给出

 [
 \frac1n=\frac1c+\frac1b。 
]

 清除分母后，

 [
 bc=n(b+c)。 
]

 重新排列给出

 [
 bc-nb-nc=0,
 ]

 两边相加 (n^2) 产生

 [
 (b-n)(c-n)=n^2。 
]

 由于 (b) 和 (c) 都必须大于 (n)，因此每个解都对应于 (n^2) 的正因式分解。 特别是，如果我们让

 [
 x=b-n,
 ]

 然后

 [
 b=n+x,\qquad c=n+\frac{n^2}{x},
 ]

 其中 (x) 是 (n^2) 的正因数。 

暴力实现可以尝试从 (n+1) 到 (n+n^2) 的每个 (b)，恢复 (c)，检查方程是否成立，并计算 (b\oplus c)。 即最坏情况下有 (O(n^2)) 个候选者。 对于 (n=10^7)，这意味着一个测试用例大约需要 (10^{14}) 次迭代，因此这种方法完全不切实际。 

有用的观察是我们实际上不需要检查除数。 因式分解告诉我们特殊的选择

 [
 x=1
 ]

 总是给予

 [
 b=n+1
 ]

 和

 [
 c=n+n^2=n(n+1)。 
]

 因此，它给出了有效的候选人

 [
 a=(n+1)\o加上n(n+1)。 
]

 剩下的问题是另一个除数 (x>1) 是否可以产生更大的 XOR。 

假设 (x\le n^2/x)，这总是可能的，因为交换两个因子仅交换 (b) 和 (c)，并且 XOR 是对称的。 对于每个 (x\ge2)，

 [
 x\le n
 ]

 和

 [
 \frac{n^2}{x}\le\frac{n^2}{2}。 
]

 因此

 [
 b=n+x\le2n
 ]

 和

 [
 c=n+\frac{n^2}{x}\len+\frac{n^2}{2}。 
]

 由于 XOR 永远不会超过其操作数之和，

 [
 b\oplus c\le b+c\le\frac{n^2}{2}+3n。 
]

 现在考虑从 (x=1) 获得的候选值。 对于任意 (u\ge v)，

 [
 u\oplus v=u+v-2(u\mathbin{&}v)\ge u-v,
 ]

 因为 (u\mathbin{&}v\le v)。 这里 (u=n(n+1)) 和 (v=n+1)，所以

 [
 (n+1)\oplus n(n+1)\ge n^2-1。 
]

 对于 (n\ge7)，

 [
 n^2-1>\frac{n^2}{2}+3n。 
]

 因此，(x\ge2) 的每个选择都严格比 (x=1) 更差。 

剩下的值（n=1,2,3,4,5,6）很小，可以直接检查。 他们的答案是(0,5,8,17,24,45)，他们也同意同样的公式。 

所以整个优化就归结为

 [
 \boxed{a=\bigl(n(n+1)\bigr)\oplus(n+1)}。 
]

 这也是该问题的公认解决方案所使用的紧凑结构。

 | ---| ---| ---| ---|
 | 蛮力 | (O(n^2)) | (O(1)) | (O(1)) | 太慢了 |
 | 最佳 | (O(1)) | (O(1)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 读取(n)的一个值。 输入最多包含 20 个这样的值，但每个测试用例都是独立的。 
2. 构建

 [
 b=n+1。 
]

 这对应于在分解 ((b-n)(c-n)=n^2) 中选择 (x=b-n=1)。 
3. 构建

 [
 c=n(n+1)。 
]

 由于 (c-n=n^2)，乘积条件变为

 [
 (b-n)(c-n)=1\cdot n^2=n^2,
 ]

 因此保证该对满足原倒数方程。 
4. 从 (c=a\oplus b) 恢复 (a)。 XOR 是自逆的，所以

 [
 a=c\o加b． 
]

 代入构造值给出

 [
 a=n(n+1)\oplus(n+1)。 
]
 5. 打印 (a)。 

我们不枚举其他除数的原因是上面的极大性论证。 对于 (n\ge7)，每个其他分解都会给出低于 (n^2/2+3n) 的 XOR，而所选结构至少为 (n^2-1)。 六个较小的值可以分别验证，并且都满足相同的公式。 

### 为什么它有效

 令(c=a\o加b)。 每个有效的解决方案都满足

 [
 \frac1n=\frac1b+\frac1c,
 ]

 这相当于

 [
 (b-n)(c-n)=n^2。 
]

构造 (b=n+1), (c=n(n+1)) 与因子对 (1,n^2) 完全对应，因此它始终有效。 对于任何其他因子对，在对因子进行排序后，我们得到 (x\ge2)，它将生成的 XOR 限制为 (n^2/2+3n)。 所选结构至少具有 XOR (n^2-1)，对于每个 (n\ge7) 来说都较大。 可以明确检查六个较小的值。 因此，没有有效的对可以产生大于构造值的 (a)。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        x = n + 1
        c = n * x
        ans.append(str(c ^ x))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```输入循环独立处理每个测试用例，与算法的第一步相匹配。 无需存储测试用例本身。 

变量`x`是(n+1)，起到(b)的作用。 产品`c = n * x`构造 (a\oplus b=n(n+1))。 最终的表达`c ^ x`然后恢复 (a)，因为

 [
 (a\oplus b)\oplus b=a。 
]

 乘法在异或之前执行。 这个顺序很重要，因为预期的表达是

 [
 (n(n+1))\oplus(n+1),
 ]

 不是 (n((n+1)\oplus(n+1)))。 

实现中没有除法，因此没有要处理的除数或余数边界情况。 Python 的任意精度整数还可以安全地处理最大中间值 (n(n+1))，当 (n=10^7) 时，该值约为 (10^{14})。

 [
 a=42\oplus7=45。

 ## 边缘情况

 对于 (n=1)，该算法计算

 [
 n+1=2,\qquad n(n+1)=2,
 ]

 所以

 [
 a=2\oplus2=0。 
]

 对应的对是 (b=2) 和 (a\oplus b=2)，给出

 [
 \frac12+\frac12=1=\frac11。 
]

 因此该算法正确地产生`0`，即使问题要求整数 (a) 并且不要求 (a) 为正数。 

对于 (n=2)，算法给出 (b=3) 和 (a\oplus b=6)。 自从

 [
 \frac16+\frac13=\frac12,
 ]

 构造是有效的，并且

 [
 a=6\oplus3=5。 
]

 这是第一个答案为肯定的情况，并确认必须包含因子 (x=1)。 

对于 (n=6)，((b-n)(c-n)=36) 可能的有序因子选择包括 (1\cdot36)、(2\cdot18)、(3\cdot12) 和 (6\cdot6)。 所选对 (1\cdot36) 给出 (b=7,c=42)，产生 (45)。 其他对给出 (8\oplus24=16)、(9\oplus18=27) 和 (12\oplus12=0)。 因此，边界情况与一般结构是一致的。 

对于(n=7)，证明开始直接适用。 对于 (x\ge2)，我们有

 [
 b\oplus c\le\frac{49}{2}+21=45.5,
 ]

 所以整数异或最多是(45)。 (x=1) 的构造给出

 [
 8\oplus56=48。 
]

 因此，构造的值严格大于每个替代值，从而给出正确的输出`48`。 

对于 (n=10^7)，构造使用

 [
 b=10000001
 ]

 和

 [
 c=100000010000000。 
]

 他们的异或是

 [
 100000010000000\oplus10000001
 =100000017825793。 
]

 该计算非常适合 Python 的整数表示形式，并且不需要搜索暴力公式建议的大约 (10^{14}) 可能值。
