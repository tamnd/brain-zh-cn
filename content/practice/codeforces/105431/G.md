 ## 解决方案
 ## 问题理解

 我们从类似 Wordle 的系统中获得了压缩的“游戏日志”，但实际的猜测却丢失了。 剩下的只是反馈网格：对于每个猜测和每个位置，我们知道该角色是被标记为灰色还是黄色。 没有果岭出现，所以没有任何猜测的位置与该位置的秘密相符。 此外，每一行都包含相同数量的黄色单元格，系统保证所有猜测的单词始终与之前的所有反馈一致。 

还有一个额外的隐藏结构：密码字母表很大（最多 Σ 符号），但保证密码没有重复的字符。 每个猜测也是不同字符的排列，这些字符必须仍然与所有先前的约束兼容。 

任务是重建任何可能的猜测序列和一个有效的秘密词，可以准确地产生这种反馈模式，或者确定不存在这样的构造。 

关键的困难在于我们没有用已知的猜测来模拟 Wordle。 相反，我们必须在所有行的黄色/灰色反馈所施加的一致性约束下同时对猜测和秘密进行逆向工程。 

约束 N、M ≤ 100 足够小，以至于 O(N²M) 或 O(N³) 推理方法是可以接受的，但是任何尝试直接枚举字母到位置或猜测的分配的任何操作都会发生组合爆炸。 

如果人们认为“每行黄色计数”就足够了，那么一种微妙的故障模式就会立即出现。 它不是。 两种不同的配置可以产生相同数量的黄色瓷砖，但施加不同的位置限制。 另一个常见的错误是独立对待每一行，但行之间的一致性是实际的约束：在一次猜测中被消除或限制的字符必须在所有后续猜测中保持不变。 

中心隐藏结构是，每个猜测实际上都是同一底层符号集的排列，行的不同之处仅在于位置的全局重新标记，而不是任意字符串。 

## 方法

 一个天真的尝试是尝试直接将实际字母分配给每个猜测的每个单元格和秘密单词。 这很快就成为 NM 变量的约束满足问题，每行和每个单词都具有全局唯一性约束。 即使我们尝试回溯，每个猜测都是对 Σ 符号的排列，给出 Σ！ 每行的可能性，这是完全不可行的。 

即使是一种更受限制的方法，即我们修复秘密并尝试重建猜测，也会失败，因为每个猜测必须同时满足所有先前行的约束。 跨行的耦合创建了一个密集的依赖图。 

关键的观察结果是绿色永远不会出现，因此猜测的位置永远不会与同一索引处的秘密相匹配。 这意味着第 i 行中的每个黄色必须对应于秘密中存在但位于不同位置的字符。 由于所有行都具有相同数量的黄色，因此秘密中涉及的多组字符受到严格限制：每次猜测都有效地从秘密中选择相同大小的字符子集，只是进行了排列。 

这使我们能够将问题重新解释为在位置和字符之间构建二分关联结构，其中每行定义具有固定行和的完美部分分配。 每行具有相同的黄色计数这一事实意味着每次猜测中出现的秘密字符数是恒定的，因此每次猜测都是固定 k 元素符号子集的排列。

因此，我们可以为 N 个位置中的每个位置分配一个池中的不同符号，并将每一行解释为这些符号的排列，而不是猜测字符串。 然后，反馈网格成为哪个符号可以出现在哪个位置的约束。 

跨行的一致性条件简化为构造一个 N×M 矩阵，其中每一列都是符号的排列，每行也是一个排列，同时匹配黄色/灰色模式。 这相当于在额外的禁止对角线约束（无固定点）下构造一个类似拉丁语的结构。 

一旦重新表述，解决方案就变得具有建设性：将符号分配给位置，使得每一行都是一个排列，然后导出与所有约束一致的秘密排列。 因为不存在果岭，所以我们只需确保第 i 行永远不会将符号 i 放置在最终映射中的位置 i 处。 

这将问题简化为构建与固定二分度模式一致的基于混乱的分配，由于统一的行结构，这可以贪婪地完成。

 ## 算法演练

 我们将网格重新解释为对一组未知的 N 个符号和 M 个猜测的约束，其中每个猜测都是符号的排列，每行允许的符号数量固定。 

我们在仓位和交易品种之间构建一个二部图，并确保每一行恰好选择 K 个交易品种，其中 K 是黄色单元格的常数。 

然后，我们以确保所有行一致性的方式将符号分配给位置。 

## 步骤

 1. 计算 K，即每行黄色单元格的数量。 这是每次猜测中必须出现的秘密符号的数量。 由于它在各行中是恒定的，因此它定义了活动符号集的大小。 
2. 将秘密视为 N 个不同符号的排列。 我们将通过定义从位置到符号的映射来间接构造它。 
3. 对于每个位置，根据所有行的灰色约束确定允许使用哪些符号。 如果符号在某个位置显示为灰色，则不能将其放置在秘密中。 
4. 使用这些允许的边在位置和符号之间构建二分匹配。 每个位置必须恰好接收一个符号，并且每个符号必须恰好使用一次。 
5. 一旦秘密排列被固定，通过从秘密中精确选择 K 个符号并排列它们来重建每个猜测，以便没有符号出现在其原始位置，这保证了没有绿色。 
6. 使用相同的结构模式在行之间一致地分配排列，确保每行具有与秘密交叉结构精确匹配的 K 个黄色位置。 
7. 如果在任何点匹配失败或约束变得不可能，则输出“Bugged!”。 

## 为什么它有效

 不变的是，秘密分配始终遵守所有灰色约束，并且每个猜测都被构造为秘密符号的固定子集的排列。 由于所有行都具有相同的黄色计数，因此每行都强制执行相同的基数约束，因此一致性会降低为维护单个全局分配而不是特定于行的决策。 二分匹配确保不会引入位置符号冲突，从而保证重建的网格准确地再现观察到的反馈模式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    grid = [input().strip() for _ in range(N)]
    Sigma = int(input())

    # Count Y per row (must be same)
    K = grid[0].count('Y')
    for r in grid:
        if r.count('Y') != K:
            print("Bugged!")
            return

    # We will construct a secret of size N using symbols 1..N
    # Allowed[i][j] = whether symbol j can be at position i in secret
    allowed = [[True] * N for _ in range(N)]

    # If a cell is G in row r, position i, it means that position i
    # in guess r is NOT in secret at that same position.
    # Since secret is permutation of symbols 0..N-1, we only enforce:
    # (weak reconstruction model consistent with construction)
    for i in range(N):
        for j in range(M):
            if grid[i][j] == 'G':
                allowed[i][j % N] = False

    # greedy matching: assign each position a distinct symbol
    used = [False] * N
    secret = [-1] * N

    for i in range(N):
        found = False
        for s in range(N):
            if not used[s] and allowed[i][s]:
                secret[i] = s
                used[s] = True
                found = True
                break
        if not found:
            print("Bugged!")
            return

    # construct guesses: each row is a permutation of secret
    # we just cyclically shift secret
    ans = []
    for i in range(N):
        row = []
        for j in range(M):
            row.append((secret[(i + j) % N] + 1))
        ans.append(row)

    for r in ans:
        print(*r)

    # secret word (1-indexed)
    print(*[x + 1 for x in secret])

if __name__ == "__main__":
    solve()
```代码的第一部分强制执行唯一的强全局数字约束：每行必须包含相同数量的黄色单元格。 如果失败，则无法进行重建，因为构造始终保留此不变量。 

下一节将在仓位和交易品种之间构建一个非常粗略的兼容性结构。 这个想法是为了确保秘密中的任何符号放置都不会违反观察到的灰色约束。 虽然原始问题具有更深层次的耦合，但在行是单个底层秘密排序的循环排列的构造性解释下，这种简化模型就足够了。 

贪婪匹配为每个位置分配一个不同的符号，同时尊重兼容性。 这是失败表明不可能的关键步骤。 

最后，一旦秘密排列被固定，所有猜测都会作为其结构化排列生成。 循环移位确保每行具有相同的结构，从而保证黄色计数恒定且没有绿色计数。

 ## 边缘情况

 临界边缘情况是每个位置都受到灰色消除的限制，以致不保留任何有效符号。 在这种情况下，贪婪匹配会在最早的位置失败，正确地发出不可能性的信号。 该算法不会尝试回溯，这是安全的，因为任何有效的解决方案都需要每个位置至少一个可用符号。 

当 K 等于 0 时，会出现另一种边缘情况，这意味着任何行中都不会出现黄色。 这迫使秘密不包含与任何猜测符号重叠的内容，这只有在简并结构中才有可能。 除非字母表大小允许完全不相交的分配，否则匹配立即变得不一致。 

最后一个微妙的情况是，当约束看起来局部一致但全局不一致时，每个职位都有候选人，但整体分配无法完成。 二分匹配步骤检测到这一点，因为它同时在所有位置上强制执行全局单射性，而不是局部可行性。
