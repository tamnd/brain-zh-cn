 ## 解决方案
 ## 问题理解

 我们给出一个矩形区域，在概念上分为单位网格位置，其尺寸$a \times b$。 我们正好有$N$相同的单位正方形瓷砖，我们必须将它们全部放置在这个网格内。 

放置受到两种结构方式的限制。 

首先，瓷砖必须形成与每个占用的单元格“向下左封闭”的形状。 如果将一块图块放置在某个单元格中，则直接位于其西边和南边方向直至场地边界的所有内容都必须已被覆盖，并且图块下方或左侧不会出现空白间隙。 这迫使被占用的单元格表现得像网格中的理想顺序：每当一个单元格$(i, j)$被使用，所有细胞$(i' \le i, j' \le j)$也必须使用。 从几何角度来看，该形状完全由其东北边界决定，并且该边界是单调的。 

其次，位于北或东方向“最外”边界的图块中，所有图块与西南原点角的曼哈顿距离必须相同。 由于曼哈顿距离$(1,1)$是$i + j - 2$，这个要求迫使每个最大边界单元位于一条对角线上$i + j = K$对于一些常数$K$。 这会将边界从任意楼梯变成直线对角线截止。 

因此，有效的形状正是通过获取完整网格并用对角线切割形成的形状$i + j \le K$，与$a \times b$矩形，并计算剩余的细胞数量。 任务是计算这样的配置可以准确产生多少种方式$N$瓷砖。 

约束条件允许$a, b \le 10^4$，所以任何迭代所有的解决方案$a \cdot b$细胞太慢了。 我们需要一个大致运行的解决方案$O(a + b)$或者$O((a + b)\log(a + b))$。 一个完整的$O(a b)$扫描大约是$10^8$，这在 Python 中是临界值或太慢。 

一个微妙的边缘情况是对角线完全位于矩形之外。 对于非常小的$K$，不包含任何单元格。 对于非常大的$K$，包括整个矩形。 另一个重要的情况是当多个连续值$K$不添加新单元格，因为没有网格点满足$i + j = K$; 在这些范围内，有效配置的数量可以跨越多个$K$值，必须正确计算。 

## 方法

 蛮力解释将尝试一切可能的方法在约束下选择有效的单调形状。 即使我们将自己限制为有效的“前缀封闭”形状，我们仍然需要枚举一个内部的所有单调边界$a \times b$网格。 该数字以组合方式增长，因为每个边界对应于从右上角到左下角的单调晶格路径。 此类路径的数量呈指数级增长$a + b$，使得暴力破解变得不可行。 

关键的结构观察是第二个条件将整个单调形状族折叠成一个单参数族。 边界必须恰好位于单个对角线上，而不是任意的楼梯边界$i + j = K$。 这消除了所有组合自由度：每个有效配置仅通过选择来确定$K$。 

一旦进行了简化，问题就变成了纯粹的算术问题。 对于每个$K$，我们计算有多少个网格点满足$i + j \le K$。 这个计数是单调的$K$，所以我们然后寻找有多少$K$值恰好产生$N$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（所有形状）| 指数| O(1) | O(1) | 太慢了 |
 | 对角扫过 K | O(a + b) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们根据对角线切割下的格点计数来重写该问题。 对于固定的$K$，我们定义$f(K)$作为整数对的数量$(i, j)$这样$1 \le i \le a$,$1 \le j \le b$， 和$i + j \le K$。 

### 步骤

 1. 计算每个对角线上有多少对$t = i + j$。 

对于每个$t$，有效对的数量是同时满足框约束和方程的整数解的数量$i + j = t$。 这是两个间隔的标准重叠。 
2. 构建数组$s[t]$， 在哪里$s[t]$计算有多少个单元格正好位于对角线上$t$。 

该数组是分段线性的：它增加，可能在矩形顶部保持平坦，然后减少。 
3. 转换$s[t]$分解为前缀和$f(t)$。 

这给出了水平切割的三角形区域内的单元数$t$。 
4. 迭代所有$t$从$2$到$a + b$, 追踪何处$f(t) = N$。 
5. 自从$f(t)$是非递减的，任何连续的段$t$值其中$s[t] = 0$创建一个平坦区域。 如果前缀和等于$N$在这样的一段上，每个$t$该段中是一个有效的配置，我们将它们全部计数。 

### 为什么它有效

 从形状到对角线的转换是有效的，因为第二个条件强制所有最大元素共享相同的值$i + j$。 这唯一地将边界确定为总和最多的所有点的集合$K$。 每个有效的配置都恰好对应一个这样的配置$K$，并且构造的单调性确保不会计算无效形状，也不会遗漏有效形状。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    N, a, b = map(int, input().split())
    
    max_sum = a + b
    
    # s[t] = number of (i, j) with i+j = t
    s = [0] * (max_sum + 1)
    
    for t in range(2, max_sum + 1):
        lo_i = max(1, t - b)
        hi_i = min(a, t - 1)
        if lo_i <= hi_i:
            s[t] = hi_i - lo_i + 1
    
    ans = 0
    pref = 0
    
    for t in range(2, max_sum + 1):
        pref += s[t]
        if pref == N:
            ans += 1
    
    print(ans % MOD)

if __name__ == "__main__":
    solve()
```实现的核心是计算每个反对角线上有多少个网格点。 对于固定金额$t$， 有效的$i$必须同时满足$1 \le i \le a$和$1 \le t - i \le b$，变成区间交集。 然后，前缀累积重建每个对角线阈值包含多少个单元。 

一个微妙的实现细节是我们从不显式构造二维网格。 一切都简化为计算每个对角线的整数范围，这使解决方案保持线性$a + b$。

 ### 示例 1

 输入：```

```认为$a = 3$,$b = 8$,$N = 3$。 我们计算对角线$t = i + j$。 

| t | s[t] | 前缀 f(t) |
 | --- | --- | --- |
 | 2 | 1 | 1 |
 | 3 | 2 | 3 |
 | 4 | 3 | 6 |

 我们正在寻找$f(t) = 3$。 这发生在$t = 3$仅有的。 

所以答案是1配置。 

该轨迹显示了当我们扫描对角线时前缀总和如何增长，以及有效配置对应于精确的前缀匹配。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：$N = 0$或者$N = 1$。 在这些情况下，只有最小的对角线起作用，答案取决于是否存在多个$K$没有添加新单元格的值。 该算法自然地处理这个问题，因为空对角线有助于$s[t] = 0$，创建平坦的前缀区域。 

另一种情况是当$N = a \cdot b$，意味着必须填充整个矩形。 仅当以下情况时才会发生这种情况$K \ge a + b$，所以只有最终的前缀和等于$N$，准确生成一种有效配置。
