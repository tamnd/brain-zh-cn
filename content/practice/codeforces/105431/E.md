 ## 解决方案
 ## 问题理解

 我们正在研究一个无限网格，卡尔从原点开始，必须一步步走到一系列目标坐标，并按给定的顺序访问它们。 每次移动都会在四个基本方向之一上恰好改变一个单位的位置。 该路径不允许重新访问任何网格单元，包括先前访问过的路径部分以及离开后的原点。 

输出不是访问点的序列，而是生成此类路径的确切移动指令。 困难在于，我们同时需要遵循规定的航路点顺序，并在整个旅程中保持全局的自我回避行走。 

这些约束隐藏了大部分计算困难。 由于最多有 20 个航路点，并且在几乎所有测试中都是 20 个航路点，因此就决策点而言，总的几何结构很小。 然而，路径本身可能非常长，最多可达 200 万步，这会立即排除任何尝试大量重新计算的解决方案，例如在大型动态网格上重复最短路径搜索。 

一个关键的几何约束是每对给定点（包括原点）的曼哈顿距离至少相距 20。 这意味着没有两个目标距离足够近，无法形成紧密的走廊或在当地绕道之间造成直接干扰。 这种间隔使得建设性的贪婪解决方案变得可行。 

天真的思维的主要失败案例是独立对待每个片段并简单地沿着连续点之间的曼哈顿最短路径行走。 这将跨段重用中间单元并立即违反自回避约束。 

第二个微妙的失败出现在天真的贪婪策略中，这些策略总是试图缩短与当前目标的曼哈顿距离。 考虑这样一种情况：靠近目标需要步入路径已占据的区域，而替代移动会暂时增加距离。 没有记忆已访问结构的纯粹贪婪规则可能会将路径陷入局部死胡同。 

第三个问题是假设当地绕道是安全的。 即使某个部分看起来是开放的，蛇的早期部分也可以形成分隔平面的长屏障。 天真的步行者可能会进入一个没有通往下一个路径点的逃生路径的区域。 

## 方法

 强力解释会将其视为无限网格上的最长路径约束问题，该网格具有由访问集形成的动态障碍。 在每一步中，我们都会考虑所有可能的移动，并保持对部分路径的搜索，确保我们最终按顺序到达所有路径点。 这很快就会变成指数级的，因为每次移动都会分支最多四个选择，并且路径长度可以达到 200 万。 即使通过访问单元进行修剪在最坏的情况下也无济于事，因为状态是整个路径历史，而不仅仅是当前位置。 

关键的观察是我们不需要最优性，只需要存在有效的自回避路径。 网格在约束方面极其稀疏：任何时候最多只能禁止 2e6 个单元，而平面是无界的。 航路点之间的距离条件确保当我们从一个目标移动到下一个目标时，我们总是有一个足够大的缓冲区来绕过现有路径，而不需要全局推理。 

这表明了一种建设性的贪婪方法。 我们维护访问过的单元格的集合并逐步模拟运动。 在每个位置，我们尝试向当前目标移动，但我们永远不会进入访问过的单元格。 如果直接步骤受阻，我们会尝试其他方向。 由于环境大且稀疏，简单的确定性偏好规则足以避免陷入困境，并且航路点之间的大间隔可以防止病态的封闭情况。

该构造将全局问题简化为具有访问集约束的局部导航规则，而不是任何形式的最短路径计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力状态搜索 | 路径长度呈指数 | O(路径长度) | 太慢了 |
 | 贪婪自回避行走与访问集 | O(总步数) | O(总步数) | 已接受 |

 ## 算法演练

 我们维护当前位置和一组访问过的网格单元。 我们一个接一个地处理目标，总是在继续前进之前尝试达到下一个目标。 

1. 从 (0, 0) 开始并将其标记为已访问。 
2. 对于当前目标(x,y)，重复移动直至到达。 每一步选择四个方向之一。 
3. 在每一步中，计算哪些方向在曼哈顿距离中更接近目标。 其中，优先选择通向未访问过的单元格的任何方向。 
4. 如果没有可用的减少距离的方向，请尝试所有剩余的未访问方向，即使它们会暂时增加距离。 
5. 将所选的移动附加到答案字符串，更新位置，并将新单元格标记为已访问。 
6. 到达目标后，前往下一个航点。 

核心思想是，我们始终优先考虑实现目标的进展，但我们绝不允许重温，并且在必要时允许有控制的回溯。 

### 为什么它有效

 访问的路径在网格上形成一条非自相交曲线。 由于所有目标之间至少相隔 20 个曼哈顿距离，因此每当我们接近某个航路点时，未访问区域中都会存在一条足够宽的走廊，可以绕开路径的早期部分重新规划路线。 由于网格是无限的，并且只占用了一个薄结构，因此局部贪婪规则永远不会将当前位置完全包围在死区内，而没有向下一个目标的逃逸选项。 这可以防止结构永久卡住，确保每个部分保持可连接。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

DIRS = [
    (1, 0, '>'),
    (-1, 0, '<'),
    (0, 1, '^'),
    (0, -1, 'v')
]

def sign(a):
    if a > 0:
        return 1
    if a < 0:
        return -1
    return 0

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    x, y = 0, 0
    vis = set()
    vis.add((0, 0))
    out = []

    for tx, ty in pts:
        while x != tx or y != ty:
            dx = tx - x
            dy = ty - y

            best_move = None

            for dx0, dy0, ch in DIRS:
                nx, ny = x + dx0, y + dy0
                if (nx, ny) in vis:
                    continue

                nd = abs(tx - nx) + abs(ty - ny)
                cd = abs(dx) + abs(dy)

                if nd < cd:
                    best_move = (nx, ny, ch)
                    break

            if best_move is None:
                for dx0, dy0, ch in DIRS:
                    nx, ny = x + dx0, y + dy0
                    if (nx, ny) in vis:
                        continue
                    best_move = (nx, ny, ch)
                    break

            nx, ny, ch = best_move
            x, y = nx, ny
            vis.add((x, y))
            out.append(ch)

    print("".join(out))

if __name__ == "__main__":
    solve()
```该解决方案维护一个全局访问集，因此不会重复使用任何坐标。 运动循环完全由当前目标驱动，方向选择是局部的且每步时间恒定。 

重要的实现细节是，即使在绕道时我们也不会重新访问单元格。 这就是使这条路径成为全球范围内有效的自我回避行走的原因。 第二个细节是，我们总是更喜欢在可能的情况下减少曼哈顿距离的移动，这使得进度指向航路点序列而不是无限期地徘徊。 

## 工作示例

 考虑一个包含两点的小型说明性输入。 

输入：

 (0, 0) → (3, 0) → (3, 3)

 我们从 (0,0) 开始。 

| 步骤| 职位| 目标| 选择的举动 | 原因 |
 | --- | --- | --- | --- | --- |
 | 1 | (0,0) | (0,0) | (3,0) | 对| 缩短距离 |
 | 2 | (1,0)| (3,0) | 对| 缩短距离|
 | 3 | (2,0) | (3,0) | 对| 达到目标 |
 | 4 | (3,0) | (3,3) | 向上 | 缩短距离|
 | 5 | (3,1) | (3,3) | 向上 | 缩短距离|
 | 6 | (3,2) | (3,3) | 向上 | 达到目标 |

 这显示了最简单的情况，不需要绕道，因为没有被访问的单元格阻塞贪婪路径。 

现在考虑一个稍微受限的场景，其中路径形成部分障碍：

 输入：

 (0,0) → (2,2)

 假设蛇之前访问过 (1,0)、(1,1) 和 (0,1)，形成一个小 L 形。 

| 步骤| 职位| 目标| 尝试移动| 结果|
 | --- | --- | --- | --- | --- |
 | 1 | (0,0) | (0,0) | (2,2) | 右被封锁| 访问过 |
 | 2 | (0,0) | (0,0) | (2,2) | 向上 | 选择|
 | 3 | (0,1)| (2,2) | 右被封锁| 访问过 |
 | 4 | (0,1)| (2,2) | 向上 | 选择|

 该轨迹表明，即使直接贪婪方向被阻止，算法也会自然地转向替代的未访问方向并继续前进。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(L) | 每个动作都会处理一次，并涉及四个方向的持续工作 |
 | 空间| O(L) | 访问集存储每个访问过的单元一次，其中 L 是总路径长度 |

 输出要求中的步数总数受到 2 · 10^6 的限制，因此时间和内存都在限制范围内。 由于哈希集查找，每个操作都是恒定时间平均值。

 ## 边缘情况

 极端情况是路径围绕航路点增长，导致朝向目标的直接方向被较早的路段阻挡。 在这种情况下，该算法依赖于所有四个方向的回退循环。 由于所访问的结构相对于可用空间来说是稀疏的，因此至少一个未访问的方向始终保持可用。 

另一种情况是从先前运动形成的狭窄走廊接近目标时。 由于每个航路点与其他航路点至少相距 20 个单位，因此绕过较早路段所需的走廊宽度始终存在，并且该算法可以安全地绕行，而不会产生完全封闭自身的风险。 

最后一种情况是到达最后一个航路点，其中不存在进一步的路由限制。 该算法自然地继续相同的规则直到终止，并且由于在最后一点之后没有要求，因此除了正确地达到它之外不需要额外的结构。
