 ## 解决方案
 ## 问题理解

 我们得到两个序列，代表两副面朝上的牌中的牌的顺序。 每副牌均包含$N \cdot K$卡，值来自范围$1$到$N$。 在每副牌中，每个值都准确出现$K$次，因此两副牌都是具有相同多重性的平衡多重组。 

我们从两副完整的牌开始，只查看它们的顶牌。 我们随时都会比较两张可见的牌。 如果它们匹配，我们将两者都删除并获得一分。 如果它们不同，我们必须丢弃最上面两张牌中的一张，露出该牌组中的下一张牌。 这个过程一直持续到两副牌都用完为止。 移除的顺序完全在我们的控制之下，任务是最大化匹配移除的数量。 

约束条件是由$N \le 10^4$和$K \le 15$，所以每副牌最多有$1.5 \cdot 10^5$元素。 这个值足够大，以至于不可能对位置进行任何二次模拟。 甚至一个$O(n^2)$方法将涉及周围$10^{10}$在最坏的情况下进行操作，这远远超出了可行的限度。 我们需要一种能够在接近线性时间或线性时间的时间内处理牌组的解决方案。 

一个微妙的困难是决策不是本地的。 选择尽早放弃一张牌会影响未来的排列，如果没有保证最优性的结构，贪婪的“尽可能匹配”直觉是不够的。 

当贪婪地匹配早期块会减少未来的对齐机会时，就会出现一种边缘情况。 例如，如果两副牌都以重复的模式开始，例如两个值交替出现，那么过早的匹配可能会导致稍后出现不匹配，从而降低总分。 另一个问题是对称情况，其中两个牌组都包含相同的多重集，但排序严重排列，使得基于指针的简单匹配无法捕获最佳配对结构。 

## 方法

 暴力解释将此视为最短路径样式的状态探索问题。 每个状态由两个索引定义$i, j$，代表每副牌中已丢弃的牌张数。 从一个状态来看，我们要么匹配 if$a[i] = b[j]$或者分为两种可能性：从第一副牌中弃牌或从第二副牌中弃牌。 这形成了一个有向无环图$(N K + 1)^2$状态，转换取决于平等。 

这种方法是正确的，因为它明确地探索了丢弃决策的每个有效序列。 然而，状态空间是二次的，并且每个状态都可以分支，除非大量记忆，否则在实践中会导致指数行为。 即使有了记忆，我们仍然面临$O((N K)^2)$州，其周围$2.25 \cdot 10^{10}$在最坏的情况下，太大了。 

关键的观察是我们永远不需要独立区分两副牌的任意前缀。 重要的是我们在每副牌中取得了多大的进展，但仅相对于匹配值的位置而言。 由于每个值仅出现$K$每副牌的次数，我们可以考虑对齐两个序列中相同值的出现。 

我们不是推理任意前缀，而是关注通过匹配相同值的出现而形成的子序列。 对于每个值，我们都会考虑它在两副牌中的位置。 任何有效的策略最终都会将两个列表之间每个值的一些出现配对，并遵守顺序。 这将问题转化为寻找事件之间非交叉匹配的最大数量，每个值单独约束但全局交错。 

这导致动态编程解释相当于在排序约束下找到匹配对的最长序列，这可以使用 Fenwick 树或基于分段的 DP 来有效解决。 因为每个值只出现$K \le 15$有时，我们可以以压缩形式对状态转换进行编码，确保每次出现的转换保持有界。 

我们将问题简化为按顺序处理事件，同时保持可实现的最佳匹配，使用 DP 跟踪同步扫描两个牌组时可以形成多少个匹配，始终选择是否以受控顺序跳过或对齐事件。 这产生了卡总数的近线性解。

 ## 算法演练

 我们处理两个牌组，同时跟踪每个值的出现并构建一个允许按顺序匹配决策的结构。 

## 算法演练

 1. 分别为两个牌组的每个值构建位置列表。 对于每个值$x$，将索引存储在甲板 A 和甲板 B 中出现的位置。这使我们能够仅根据出现顺序而不是原始序列进行推理。 
2. 对于每个值$x$，将其出现视为两个有序列表。 目标是选择配对$(i, j)$使得 A 和 B 中的索引递增，并且每次出现最多使用一次。 这将局部问题简化为在单调约束下匹配两个序列。 
3. 构造一个全局事件列表，其中包含由值和牌组标识符标记的所有事件。 按每个牌组中的位置对该列表进行排序。 然后，我们模拟一个尊重两个序列中原始顺序约束的扫描。 
4. 维护一个 DP 结构，记录在两副牌的给定前缀下可实现的最大匹配数。 在每一步中，我们决定是匹配当前出现的相同值还是跳过一侧。 DP 转换由先前计算的最佳状态引导。 
5. 在扩展匹配时，使用由压缩出现状态索引的芬威克树或平衡结构来查询最佳兼容的先前配置。 这确保我们只扩展单调配对。 
6. 最终答案是处理所有出现的情况后达到的最佳DP值，代表匹配删除的最大数量。 

### 为什么它有效

 关键的不变量是任何有效的操作序列都对应于相同值的配对，使得配对索引在两个牌组中保持相对顺序。 每次我们选择匹配两张卡片时，我们都会承诺从每个列表中对齐一张未使用的卡片。 每次我们丢弃时，我们实际上就跳过了潜在的配对候选者。 

因为事件是按顺序处理的，所以我们永远不会以违反单调性的方式重新考虑跳过的配对。 DP 确保每个状态都代表可行的部分匹配，并且每个转换都与两副牌的顺序保持一致。 由于所有有效的解决方案都对应于一些单调配对，并且DP探索所有单调扩展，因此总是达到最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    posA = [[] for _ in range(n + 1)]
    posB = [[] for _ in range(n + 1)]

    for i, x in enumerate(a):
        posA[x].append(i)
    for i, x in enumerate(b):
        posB[x].append(i)

    # We compress each value's occurrences into pairs of indices
    # and run DP over matched prefixes of occurrences.
    #
    # dp[i][j] conceptually = best matches using i-th occurrences in A
    # and j-th occurrences in B, but we compress per value.

    import bisect

    # For each value, we try to match occurrences greedily via LIS-style DP
    events = []

    for v in range(1, n + 1):
        for i in range(min(len(posA[v]), len(posB[v]))):
            events.append((posA[v][i], posB[v][i]))

    # Sort by A index, then B index
    events.sort()

    # LIS on B indices
    dp = []

    for _, y in events:
        idx = bisect.bisect_left(dp, y)
        if idx == len(dp):
            dp.append(y)
        else:
            dp[idx] = y

    print(len(dp))

if __name__ == "__main__":
    solve()
```该实现为每个值构建直接候选配对，然后将问题简化为在按第一副牌位置排序后找到第二副牌位置上的最长递增子序列。 每对代表一个潜在的匹配，保留两副牌中的顺序。 

LIS 步骤确保我们选择非交叉匹配的最大子集。 使用`bisect_left`保持最小尾部以增加子序列，保证最佳基数。 

一个微妙的点是我们只将$i$- 值在两个牌组中都出现，而不是所有组合。 这是有效的，因为最佳匹配永远不会从同一值内的交叉出现中受益，因为每个值都贡献独立的有序约束。

 ## 边缘情况

 一种重要的边缘情况是两个牌组都包含相同的多集内容，但顺序相反。 在这种情况下，贪婪匹配会提前失败，因为顶部元素永远不会对齐，并且只有仔细的全局排序才能揭示真正的最大匹配。 LIS 结构自然可以处理这个问题，因为反向排序不会产生递增的子序列。 

另一种极端情况是所有卡都相同。 每对都是有效的，并且排序约束无关，所以答案很简单$N \cdot K$。 该算法处理此问题是因为所有对共享相同的值排序，从而在 B 中生成完整的递增子序列。 

第三种情况是高度交错的模式，例如两个值交替出现。 局部贪婪匹配可能会锁定次优配对，但基于全局排序的 LIS 可以避免过早提交并保留最佳的单调结构。
