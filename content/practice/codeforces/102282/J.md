 ## 解决方案
 ## 问题理解

 我们有两个字符串，`s1`和`s2`。 第一个字符串是应该复制的文本，第二个字符串是实际写入的文本。 在复制过程中，允许出现两种错误：一个字符被省略，或者一个字符被另一个字符替换。 我们需要将此类错误的数量降到最低`s1`进入`s2`。 

这两种操作之间的区别很重要。 我们不允许插入新字符`s1`。 最后，`s2`不能长于`s1`，并且该问题保证给定的对在这些规则下有效。 无论涉及哪两个字母，替换都会导致一个错误，而省略一个字符也会导致一个错误。 

两个字符串的长度最多为 1024。因此，二次算法最多执行大约一百万次状态转换，这在一秒的限制内很容易管理。 然而，即使在这么小的长度下，对所有可能的字符串对齐方式进行指数搜索也会变得不必要的昂贵。 

有几种边界情况可能会导致粗心的实现不正确。 如果字符串已经相等，例如```
abc
abc
```答案是`0`。 计算字符不同位置而不考虑跳过字符的可能性的实现在这里很好，但在更一般的情况下会失败。 

跳过的字符可以出现在开头或结尾。 例如，```
abc
bc
```有答案`1`，因为第一个`a`可以省略。 相似地，```
abc
ab
```有答案`1`，因为最终`c`可以省略。 仅比较等长位置的方法无法正确表示任一操作。 

两个匹配字符之间也可能出现跳过的字符：```
abc
ac
```答案又是`1`， 因为`b`被省略。 立即处理的贪婪实现`b`和`c`作为替代品将获得`1`这是巧合，但更复杂的字符串可能会使这种局部决策不是最优的。 

最后，替换和删除可以发生在同一前缀中。 例如，```
abcd
acd
```只需要一个错误，删除`b`。 DP 公式必须区分匹配当前字符、删除当前字符`s1`，并替换当前字符。 将每个不匹配视为替换会失去以后进行更便宜的对齐的可能性。 

## 方法

 最直接的暴力破解想法是枚举两个字符串之间所有可能的对齐方式。 当当前字符相等时，即可匹配。 当它们不同时，有几种可能：替换当前字符`s1`，或者删除它并尝试匹配相同的字符`s2`反对后来的立场`s1`。 递归地探索这些选择是正确的，因为每个有效的错误序列都对应于通过该决策树的一条路径。 

这种方法的问题是相同的后缀会出现多次。 包含许多错配的序列可以在替换和删除之间重复分支。 在最坏的情况下，递归路径的数量呈指数增长，大致为`O(2^n)`对于一个长度的字符串`n`。 和`n = 1024`，这是完全不可行的。 

关键的观察是，子问题的结果仅取决于两个位置，而不取决于导致那里的整个历史。 假设我们已经处理了第一个`i`的字符`s1`和第一个`j`的字符`s2`。 这些位置之前的所有内容都已完成，因此唯一相关的信息是货币对`(i, j)`。 

这将问题转化为动态规划。 让`dp[i][j]`是转换第一个所需的最小错误数`i`的字符`s1`进入第一个`j`的字符`s2`。 

来自州`(i, j)`，有三种可能的方法来完成当前的字符。 我们可以匹配`s1[i-1]`和`s2[j-1]`如果它们相等则成本为零，或者替换`s1[i-1]`和`s2[j-1]`如果它们不同，则成本为 1。 我们也可以删除`s1[i-1]`，移动到`(i-1, j)`并花费一。 

没有对应于插入的转换`s1`，因为插入不是允许的错误之一。 这是与通常的完整编辑距离问题的唯一显着区别。 

暴力递归之所以有效，是因为它明确地探索了这些相同的选择。 动态编程只是认识到许多不同的递归路径到达相同的结果`(i, j)`陈述并存储其最佳答案一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(2^n)`在最坏的情况下|`O(n)`递归深度 | 太慢了|
 | 最佳DP |`O(nm)`|`O(nm)`| 已接受 |

 ## 算法演练

 1. 让`n = len(s1)`和`m = len(s2)`。 创建一个 DP 表，其中`dp[i][j]`表示转换所需的最小错误数`s1[:i]`进入`s2[:j]`。 
2. 初始化`dp[0][0] = 0`。 将一个空前缀转换为另一个空前缀不会出现任何错误。 
3. 初始化第一列`dp[i][0] = i`。 如果目标前缀为空，则第一个的每个`i`的字符`s1`必须删除，所以确切地说`i`错误是必要的。 
4. 初始化第一行`dp[0][j]`对每个人来说都是不可能的`j > 0`。 空源字符串无法生成非空目标，因为插入不是允许的操作。 我们可以用非常大的值来表示这些状态。 
5. 处理每个状态`(i, j)`和`i >= 1`和`j >= 1`。 首先考虑消耗两个当前角色。 如果`s1[i-1] == s2[j-1]`，这会导致零额外错误。 否则，用一个字符替换另一个字符会花费 1 个字符。 
6.同时考虑删除`s1[i-1]`。 这改变了状态`(i, j)`到`(i-1, j)`并添加一个错误。 
7、字符匹配或替换与删除之间取较小代价。 结果值是最佳答案`dp[i][j]`。 
8.填表后，输出`dp[n][m]`，表示将整个第一个字符串转换为整个第二个字符串。 

### 为什么它有效

 不变的是`dp[i][j]`始终存储尽可能少的错误数，以精确转换第一个`i`的字符`s1`正好进入第一个`j`的字符`s2`。 

考虑状态的最佳转换`(i, j)`。 它的最终操作必须消耗两个最后一个字符，这意味着它们匹配或一个被另一个替换，或者删除源前缀的最后一个字符。 这些正是递归所考虑的转换。 由于每个转换精确地增加了其最终操作的成本，并且前一个状态本身通过 DP 不变量是最优的，因此在转换中取最小值给出了最优值`(i, j)`。 基本情况涵盖涉及空前缀的所有转换，因此不变式适用于整个表，并且最终状态是所需的最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s1 = input().strip()
    s2 = input().strip()

    n = len(s1)
    m = len(s2)

    INF = n + m + 1

    dp = [[INF] * (m + 1) for _ in range(n + 1)]
    dp[0][0] = 0

    for i in range(1, n + 1):
        dp[i][0] = i

    for i in range(1, n + 1):
        for j in range(1, m + 1):
            cost = 0 if s1[i - 1] == s2[j - 1] else 1

            # Match the two characters, or replace s1[i - 1].
            dp[i][j] = dp[i - 1][j - 1] + cost

            # Delete s1[i - 1].
            dp[i][j] = min(dp[i][j], dp[i - 1][j] + 1)

    print(dp[n][m])

if __name__ == "__main__":
    solve()
```前两个输入行包含两个字符串，因此`strip()`足以删除其尾随换行符。 输入格式中没有多个测试用例。 

DP表有`(n + 1) * (m + 1)`州。 第一列初始化为`i`因为转换`s1[:i]`变成空字符串需要删除所有`i`人物。 

第一行位于`INF`除了`dp[0][0]`。 这是故意的。 仅使用删除和替换不能从空源构建正长度目标。 使用显式不可能值可以防止意外转换产生插入操作。 

对于每个普通状态，`cost`是零或一。 如果当前角色同意，那么吃掉他们两个就不需要任何成本。 如果他们不同意，则消耗两者相当于一种替代。 第二个转换删除当前源字符并保持目标位置不变。 

指数使用`i - 1`和`j - 1`因为`dp[i][j]`描述长度前缀`i`和`j`。 这是实现中主要的一对一细节。 Python整数没有溢出问题，最大的有意义的答案是`n`，因为有效输入保证`s2`可以通过删除字符并替换字符来获得`s1`。 

## 工作示例

 对于第一个示例，字符串是`flash`和`flesh`。 相关的DP状态可以如下追踪。

 | 1 | 1 | f | f | 0 | 2 | 0 |
 | 2 | 2 | 我| 我| 0 | 2 | 0 |

 这两个字符串在所有地方都一致，除了`a`相对`e`。 更换`a`和`e`花费一个错误，所以最终状态是`dp[5][5] = 1`。 

对于第二个示例，字符串是`bread`和`beer`。 长度不同，因此至少需要删除一项。 

|`i`|`j`|`s1[i-1]`|`s2[j-1]`| 匹配/更换成本| 删除成本 |`dp[i][j]`|
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 乙| 乙| 0 | 2 | 0 |
 | 2 | 2 | r | 电子| 1 | 1 | 1 |
 | 3 | 2 | 电子| 电子| 0 | 1 | 1 |
 | 4 | 3 | 一个 | 电子| 1 | 2 | 1 |
 | 5 | 4 | d | r | 1 | 2 | 2 |

 重要的过渡位于琴弦的中间。 而不是更换`r`和`e`并失去有用的对齐，DP可以删除`r`然后匹配原来的`e`。 剩余的字符可以与另外一个替换对齐，从而最少出现两个错误。

 ## 边缘情况

 第一个边界情况是开头的删除。 为了```
abc
bc
```DP 达到`dp[1][0] = 1`，代表删除`a`。 从那里开始，`b`比赛`b`和`c`比赛`c`， 所以`dp[3][2] = 1`。 逐个位置比较会看到`a != b`并错误地将第一个操作描述为替换，即使最佳对齐是删除。 

最后的删除由 DP 的第一列处理。 为了```
abc
ab
```国家`dp[2][2]`变为零，因为`ab`已经匹配了。 搬家自`(2, 2)`到`(3, 2)`使用删除转换，产生`dp[3][2] = 1`。 该算法不需要最终字符的特殊情况，因为相同的递归可以自然地处理它。 

中间的删除说明了为什么 DP 必须保留替代对齐方式。 为了```
abc
ac
```最优路径匹配`a`, 删除`b`，然后匹配`c`。 对应的状态是`dp[1][1] = 0`,`dp[2][1] = 1`， 和`dp[3][2] = 1`。 贪婪的不匹配处理程序可能会取代`b`和`c`，但 DP 保留两种可能性并选择更便宜的延续。 

对于相等的单字符字符串，```
a
a
```对角线过渡的成本为零，给出`dp[1][1] = 0`。 这会检查匹配的字符永远不会被计为错误。 

在最大输入大小下，考虑两个由 1024 组成的相同字符串`a`人物。 每个对角线转换的成本为零，因此在大约一百万次恒定时间状态更新后，最终答案仍然为零。 该算法直接根据规定的长度范围进行缩放，并且不依赖于递归深度或指数分支。 

相反的极端是 1024 个字符的源和一个字符的目标：```
aaaaaaaa...
a
```第一列记录删除任意源前缀的成本，DP可以保留一个`a`作为匹配的目标字符，同时删除其他 1023 个字符。 最终的答案是`1023`，确认空目标的初始化和删除转换在最大边界上正确工作。
