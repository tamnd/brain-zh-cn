 ## 解决方案
 ## 问题理解

 一只蜗牛从高度 0 出发，爬上富士山，富士山的高度固定为 3776 米。 每天它都会准确地爬升`n`米。 如果在攀爬后它还没有到达顶峰，那么第二天晚上它就会滑落`m`米。 问题是蜗牛需要多少天才能达到 3776 的高度，或者它是否永远也无法到达。 

输入包含白天爬升`n`和夜间滑梯`m`。 这两个值都可以大到 (10^9)，但山的高度本身只有 3776。输出要么是蜗牛到达山顶的第一天，要么是单词`NEVER`。 

的大界限`n`和`m`不要强制使用复杂的数据结构或迭代算法。 事实上，山峰的高度是如此之小且固定，即使是直接逐日模拟，在最慢的情况下也最多执行 3776 次攀爬，当`n = 1`和`m = 0`。 对于一秒的限制来说这是很小的。 尽管如此，算术解决方案更简单并且运行时间恒定。 

有几种边界情况可能会使简单的公式出错。 如果`n >= 3776`，蜗牛在第一天就到达了山顶。 例如，与`3776 100`，答案是`1`，因为蜗牛在第一次白天攀爬时就达到了 3776 的高度，并且从未在山上过夜。 

如果`n <= m`和`n < 3776`，蜗牛永远不可能永远向顶峰前进。 例如，`5 5`给出`NEVER`。 在每个完整的昼夜周期之后，蜗牛都会回到相同的高度。 和`5 6`，每次循环后它都会失去更多的高度。 

另一个常见的错误是应用每日净进度公式而不单独处理最终爬升。 为了`5 4`，经过一整天一夜的净进步只有1米，但蜗牛在最后一次白天攀爬时到达了山顶，之后并没有滑落。 正确答案是 3772，而不是 3776。 

案例`n = 0`也属于不可能的范畴。 例如，`0 0`产生`NEVER`，因为蜗牛永远不会离开起始高度。 

## 方法

 一个简单的解决方案是模拟蜗牛。 从高度零开始并重复添加`n`。 如果新高度至少为 3776，则当天就是答案。 否则，减去`m`代表夜晚并继续第二天。 这完全遵循物理过程，因此其正确性是直接的。 

模拟的最大天数仅为 3776。最慢的爬升情况是`n = 1, m = 0`，在第 3776 天达到顶峰。因此，暴力方法最多执行 3776 次迭代，远低于一秒竞争性编程程序可以处理的速度。 (10^9) 的巨大上限`n`和`m`不会增加迭代次数，因为大`n`只会让蜗牛更快完成。 

算术解决方案来自于将完整的昼夜周期与最后一天分开。 在最后一次攀爬之前，蜗牛始终位于峰顶以下，因此一整天之后的一夜会改变其高度`n - m`。 如果`n <= m`，这种变化是非积极的，除非蜗牛在第一天立即到达山顶，否则不可能到达山顶。 

认为`n > m`和`n < 3776`。 后`k`完整的日日夜夜，蜗牛处于高度

 [
 k(n-m)。 
]

 我们需要最少数量的完整循环，然后第二天的攀登才能到达顶峰：

 [
 k(n-m) + n \ge 3776。 
]

 等价地，

 [
 k(n-m) \ge 3776-n。 
]

 最小的这样`k`是

 [
 k = \left\lceil \frac{3776-n}{n-m} \right\rceil。 
]

 由于最后的攀登发生在第二天，所以答案是`k + 1`。 

上限除法可以用整数算术来执行，如下所示`(a + b - 1) // b`为积极的`a`和`b`。 这里给出

 [
 \frac{3776-n + (n-m)-1}{n-m}
 ]

 使用整数除法。 

这两种方法具有以下复杂性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(3776)，实际上是 O(1) | O(1) | O(1) | 已接受 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 算术版本更可取，因为它直接表达了底层推理并避免维持模拟高度。 

## 算法演练

 1. 阅读`n`和`m`。 这些是白天的攀爬和夜间的滑梯。 
2.如果`n >= 3776`， 打印`1`。 蜗牛在第一次攀爬时就到达了山顶，因此无需考虑夜间活动。 
3.如果`n <= m`， 打印`NEVER`。 自从`n < 3776`经过上次检查后，蜗牛第一天就无法登顶。 每个完整的昼夜周期都会改变其高度`n - m <= 0`，所以从长远来看永远不可能接近顶峰。 
4. 否则，计算一个完整昼夜周期的净增益：`n - m`。 该值为正值，因此重复循环最终会将蜗牛移动到足够高的位置。 
5. 计算最终爬升之前所需的完整循环数`cycles = (3776 - n + (n - m) - 1) // (n - m)`。 

分子代表一天爬升后仍然缺失的高度，上限除法找到可以覆盖缺失高度的最小完整周期数。 
6. 打印`cycles + 1`。 额外的一次是最后一次白天攀登，在此期间蜗牛实际上到达了山顶。 

### 为什么它有效

 关键的不变量是，在每一个完整的白天和夜晚之后，虽然蜗牛还没有到达山顶，但它的高度恰好增加了`n - m`。 什么时候`n <= m`，这种增加是非正的，因此没有任何完整的循环序列可以使蜗牛达到它在第一天无法达到的高度。 什么时候`n > m`， 后`cycles`完整的循环高度恰好是`cycles * (n - m)`，所选择的上限划分使其成为再添加一次白天爬升达到 3776 的最小周期数。由于最后一天没有第二天的夜晚，因此答案恰好是`cycles + 1`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

HEIGHT = 3776

def solve():
    n, m = map(int, input().split())

    if n >= HEIGHT:
        print(1)
        return

    if n <= m:
        print("NEVER")
        return

    gain = n - m
    remaining = HEIGHT - n

    cycles = (remaining + gain - 1) // gain
    print(cycles + 1)

if __name__ == "__main__":
    solve()
```常数`HEIGHT`存储固定的峰顶高度，这使得公式更易于阅读，并避免通过代码分散值 3776。 

必须在不可能条件之前检查第一个条件。 如果`n`至少为 3776，即使在以下情况下，蜗牛也会立即成功`m`远大于`n`。 例如，`3776 1000000000`仍有答案`1`，因为夜间滑行只有在蜗牛已经到达山顶之后才会发生。 

在排除了首日成功的案例后，`n <= m`意味着每个完整周期都有非积极的进展。 蜗牛不可能无限地攀登顶峰，所以`NEVER`是正确的。 

对于剩下的情况，`gain`是严格正数。 变量`remaining`是第一次白天攀爬后仍需要的距离。 上限除法可确定需要多少个完整周期才能覆盖该距离。 决赛`+ 1`解释了这些完整周期后发生的白天爬升。 

Python整数具有任意精度，因此即使输入值可以达到（10^9），也不存在溢出问题。 该计算还始终使用整数运算，避免了浮点舍入问题。

 ## 边缘情况

 对于`0 0`，第一天的情况`n >= 3776`是假的，并且`n <= m`是真的。 算法打印`NEVER`。 模拟也将永远保持在零高度，因此结果是一致的。 

为了`3776 1000000000`，蜗牛在第一次白天的运动中准确地爬到了山顶。 算法打印`1`在检查是否之前`n <= m`。 这种顺序很重要，因为一旦登顶，夜间的巨大滑坡就变得无关紧要了。 

为了`1 0`，每天贡献一米，没有夜间滑梯。 蜗牛在第 3776 天到达 3776 米。公式为`gain = 1`,`remaining = 3775`， 所以`cycles = 3775`结果是`3776`。 这是对于固定山高的最大可能答案。 

为了`10 10`，每个完成的昼夜循环的净变化为零。 由于蜗牛第一天只爬到 10 米，因此它永远不会达到 3776。`n <= m`条件在除法之前捕获这种情况，这也可以防止分母为零。 

为了`5 4`，蜗牛在第 3772 天到达顶峰。该公式仅使用完整周期的一米净增益，然后单独添加最终的白天爬升。 将每天视为一个完整的周期会错误地计算登顶后的夜间滑行并产生错误的答案。
