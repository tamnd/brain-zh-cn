 ## 解决方案
 ## 问题理解

 我们需要计算正整数`1`通过`r`与 互质`n`。 当两个数的最大公约数正好是时，它们互质`1`。 

输入包含两个整数，`n`和`r`, 每个最多`10^9`。 的价值`r`足够大以至于单独检查每个数字是不可行的。 即使一个最大公约数计算非常便宜，迭代所有`10^9`候选人将需要最多`10^9`gcd 计算。 因式分解`n`更有前途，因为`n <= 10^9`，所以试除法只需要考虑除数`sqrt(n) <= 31623`。 一旦不同的质因数`n`已知，最多可以有九个，因为前十个素数的乘积已经超过`10^9`。 

主要的边缘情况是`n = 1`。 每个正整数都与`1`，所以对于`1 5`答案是`5`。 一个盲目假设的公式`n`至少有一个质因数可能会意外返回零或错误地保持其初始答案不变。 

边界`r`必须具有包容性。 为了`n = 2, r = 2`，正在考虑的数字是`1`和`2`，并且仅`1`与 互质`2`，所以答案是`1`。 一个循环结束`range(1, r)`会不小心排除`r`并且对于许多输入碰巧给出了错误的结果。 

重复的质因数也必须正确处理。 为了`n = 12, r = 12`，相关素因数只有`2`和`3`， 不是`2, 2, 3`。 答案是`4`，对应于`1, 5, 7, 11`。 将重复因素视为单独的包含-排除选择会多次计算相同的禁止条件。 

最终的边界情况是`n`本身比`r`。 为了`n = 7, r = 3`, 所有三个数字`1, 2, 3`与 互质`7`，所以答案是`3`。 没有理由根据规模来限制候选人`n`; 只有它们的公约数才重要。 

## 方法

 直接的解决方案是检查每个整数`x`从`1`通过`r`并测试是否`gcd(x, n) = 1`。 这是正确的，因为所需集合的定义正是 gcd 条件。 然而，随着`r = 10^9`，该算法可以执行`10^9`gcd 计算。 尽管欧几里得算法本身很快，但十亿次迭代远远超出了预期的时间预算。 

有用的观察是，是否`x`与 互质`n`仅取决于不同的质因数`n`。 假设这些素数是`p1, p2, ..., pk`。 整数无法与`n`恰好当它可以被这些素数中的至少一个整除时。 

我们可以使用包含-排除来计算可被至少一个禁止素数整除的整数。 对于不同质因数的每个非空子集，令`d`是该子集中素数的乘积。 子集中每个素数能整除的数恰好是`d`，所以有`r // d`其中`1`通过`r`。 

对于包含奇数个素数的子集，将这些倍数相加。 对于包含偶数个素数的子集，将它们相减。 如果`bad`是结果计数，所需的答案是`r - bad`。 

剩下的唯一任务是找到不同的质因数`n`。 试除平方根就足够了`n <= 10^9`。 在提取出每次出现的素数因子后，我们只保留该素数一次，因为包含-排除需要不同的整除条件。 

通过欧拉的 totient 函数还有一个有用的等价解释。 如果上限恰好是`n`，答案是`phi(n)`。 这里间隔以任意结束`r`，所以通常的闭式公式为`phi(n)`还不够。 包含-排除直接适用于任意`r`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(r log n)`|`O(1)`| 太慢了 |
 | 最佳|`O(sqrt(n) + 2^k)`|`O(k)`| 已接受 |

 这里`k`是不同质因数的数量`n`。 自从`n <= 10^9`,`k <= 9`，所以子集枚举最多有`512`案例。 

## 算法演练

 1. 因式分解`n`通过尝试除数`2`通过`sqrt(n)`。 每当除数`p`除以当前值`n`， 记录`p`一次并反复将其分开。 删除所有副本是必要的，因为只有素数的存在才关系到互质性。 
2. 试除后，若剩余值大于`1`，将其记录为另一个素因数。 剩余值大于`1`不能有更小的未处理因子，因此它本身必须是素数。 
3. 枚举不同质因数的每个子集。 对于一个子集，将其选定的素数相乘，得到`d`。 可被每个选定素数整除的整数恰好是`d`, 给予`r // d`这样的整数。 
4.添加`r // d`当子集包含奇数个素数时，当子集包含偶数个素数时减去它。 这是针对可整除条件之间重叠的包含-排除校正。 
5. 减去非互质整数的个数`r`。 剩余的计数正好是整数的个数`[1, r]`谁的gcd与`n`等于`1`。 

### 为什么它有效

 让`P`是一组不同的质因数`n`。 一个整数`x`不与`n`恰好当至少有一个素数时`P`划分`x`。 因此不需要的整数形成集合的并集`A_p = {x : p divides x}`为了`p`在`P`。 

对于这些素数的任何子集与乘积`d`，它的交集恰好包含`d`，并且有`r // d`这样的整数直到`r`。 包含-排除通过根据子集大小交替加法和减法来精确计算并集。 最后，`bad`恰好是与以下对象共享非平凡除数的整数的数量`n`， 和`r - bad`精确计算互质整数。 

因式分解阶段提供了每个素数`P`恰好一次，因此包含-排除阶段代表每个可能的公素因数，并且没有不相关的条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, r = map(int, input().split())

    x = n
    primes = []

    p = 2
    while p * p <= x:
        if x % p == 0:
            primes.append(p)
            while x % p == 0:
                x //= p
        p += 1 if p == 2 else 2

    if x > 1:
        primes.append(x)

    k = len(primes)
    bad = 0

    for mask in range(1, 1 << k):
        product = 1
        bits = 0

        for i in range(k):
            if mask & (1 << i):
                product *= primes[i]
                bits += 1

        count = r // product

        if bits % 2 == 1:
            bad += count
        else:
            bad -= count

    print(r - bad)

if __name__ == "__main__":
    solve()
```首先复制代码`n`进入`x`，因为反复试除会减少被分解的数量。 名单`primes`每个不同的质因数恰好包含一次。 

循环开始于`p = 2`，然后仅检查之后的奇数值`2`。 这甚至可以避免测试不能为素数的除数。 条件`p * p <= x`是安全的，因为如果`x`具有复合因式分解，其因数之一至多是其平方根。 当循环结束时，剩余`x > 1`必须是素数。 

子集循环使用位掩码。 少量`i`确定是否`primes[i]`属于当前子集。`product`成为所选素数的乘积，而`bits`记录子集大小并确定包含-排除符号。 

计算采用整数除法`r // product`， 不是`(r - 1) // product`， 因为`r`本身属于区间。 Python 整数也消除了对溢出的任何担忧，尽管这里的所有中间产品对于普通 64 位整数来说也足够小。 

为了`n = 1`，因子列表仍为空。 子集循环没有迭代，所以`bad = 0`答案就变成了`r`，这是完全正确的。

 ## 边缘情况

 对于`n = 1, r = 5`，因式分解产生一个空列表，因为`1`没有素因数。 不存在包含-排除子集，因此`bad`保持为零。 最终计算结果为`5 - 0 = 5`，正确计算每个数字`1`到`5`。 

为了`n = 2, r = 2`，因子列表为`[2]`。 单个子集表示可被整除的数字`2`， 和`2 // 2 = 1`。 因此，一位候选人被拒绝，答案是`2 - 1 = 1`。 这证实了上端点`r`包括在内。 

为了`n = 12, r = 12`，因式分解产生`[2, 3]`， 不是`[2, 2, 3]`。 包含-排除计数`6`的倍数`2`,`4`的倍数`3`，并减去`2`的倍数`6`。 因此`bad = 6 + 4 - 2 = 8`, 给予`12 - 8 = 4`。 四个有效值是`1, 5, 7, 11`。 

为了`n = 7, r = 3`，因式分解产生`[7]`， 但`3 // 7 = 0`。 没有编号最多`3`可以整除`7`， 所以`bad = 0`答案是`3`。 这说明了为什么即使每个候选都小于`n`。 

对于最大尺寸的情况`n = r = 10^9`，不同的因素是`2`和`5`。 坏数是`500000000 + 200000000 - 100000000 = 600000000`，离开`400000000`有效数字。 该算法无需迭代任何一个即可达到此结果`10^9`候选整数。
