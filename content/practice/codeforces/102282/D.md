 ## 解决方案
 ## 问题理解

 我们有一个最多包含（100 × 100）个单元格的矩形网格。 有些牢房有墙，无法进入，而其余牢房则可以穿过。 一个可遍历的单元最初包含机器人。 一条命令使机器人在四个方向之一上精确移动一个单元，并且只有当每次移动都停留在网格内并落在可遍历单元上时，程序才有效。 

我们需要计算长度最多为 (l) 的所有非空程序，其中 (l \le 30)，以便执行整个程序将机器人返回到其起始单元。 不同的命令序列是不同的程序，即使它们碰巧访问相同的单元。 

答案不以任何值取模。 长度最多为 30 的程序的最大可能数量约为 (4^{30})，大约为 (1.15 \cdot 10^{18})，因此实现需要能够表示超过 32 位的值的整数运算。 Python 整数直接处理这个问题。 

网格只有 (10^4) 个单元，最大程序长度仅为 30。这强烈表明我们应该为每个单元和每个可能的长度保留一些状态。 与 (nml) 或 (4nml) 成比例的计算很容易足够小。 相比之下，枚举每个命令序列需要 (l) 中的指数时间，这在 (l=30) 时变得不可能。 

在某些情况下，看似合理的实现可能会给出错误的答案。 

考虑尽可能最小的迷宫：```
1 1 1
*
```正确答案是`0`。 空序列将使机器人返回到其初始单元，但问题明确排除空程序。 如果实现以零移动后开始的方式数量开始其答案并包含它，则会错误地输出`1`。 

第二个例子是：```
1 3 2
=*.
```机器人从中间开始。 它可以向右移动，然后向左移动，因此长度最多为 2 的唯一有效程序是`ПЛ`。 该计划`ЛП`无效，因为它的第一个命令立即进入墙壁。 正确的输出是`1`。 仅检查最终位置的模拟，不会在中间移动碰壁时立即拒绝程序，可以计算无效程序。 

第三种情况展示了允许长度的边界：```
2 2 1
*.
..
```不存在返回起始单元格的单命令程序。 每次移动都会改变曼哈顿距离从一开始的奇偶性，因此只有在偶数次移动之后才可能返回。 正确的输出是`0`。 一种常见的差一错误是对初始状态进行计数或意外处理一个额外的转换。 

## 方法

 直接的方法是生成长度从 1 到 (l) 的每个命令序列。 对于每个序列，从起始单元模拟机器人。 如果每次移动都停留在网格内并避开墙壁，请检查最终单元格是否是起始单元格。 

这是正确的，因为每个可能的程序都只生成一次，并且模拟精确地遵循迷宫的规则。 问题在于序列的数量。 有 (4^k) 个长度为 (k) 的程序，因此所有相关长度的程序数为

 \frac{4^{31}-4}{3},
 ]

 已经是 (1.5 \cdot 10^{18}) 左右。 由于模拟程序需要 (O(k)) 次操作，因此总工作实际上是 (\Theta(l4^l))，大约为 (4.5 \cdot 10^{19}) 在 (l=30) 处进行基本运动检查。 模拟本身的任何优化都无法使这种方法变得可行。 

暴力破解包含如此多重复工作的原因是许多不同的程序在执行相同数量的命令后到达相同的单元格。 一旦两个前缀在恰好 (k) 次移动后到达同一单元格，它们未来的可能性是相同的。 继续程序所需的唯一信息是当前单元格和已使用的命令数。 将机器人带到那里的确切前缀不再重要。 

这一观察直接导致了动态规划。 让`dp[r][c]`表示在单元格 ((r,c)) 处结束的当前长度的有效程序数。 最初，在任何命令之前，只有一种方法可以到达起始单元格，因此`dp[start] = 1`。 为了构造一个命令更长的程序，每个有效状态都可以移动到其最多四个可遍历的邻居中的每一个。 我们将其计数添加到相应的下一个状态。 

在计算完 (k) 个命令的状态后，起始单元格的值恰好是返回原点的长度为 (k) 的有效程序的数量。 对 (k=1,\dots,l) 的该值求和即可得到所需的答案。 初始状态不会添加到答案中，因此空程序将被自动排除。 

蛮力方法之所以有效，是因为它明确地代表了每个程序，但也失败了，因为许多程序可以共享相同的中间状态。 只有当前单元格和当前长度影响所有未来移动的观察结果让我们将所有此类前缀合并到一个 DP 状态中。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (\Theta(l4^l)) | (O(l)) 一条模拟路径 | 太慢了 |
 | 最佳| (O(1nm)) | (O(nm)) | 已接受 |

 ## 算法演练

 1. 读取网格并找到唯一的起始单元格。 对待`.`和`*`作为可遍历的单元格，同时`=`是一堵墙。 起始单元本身是可遍历的，因为机器人放置在那里。 
2. 创建二维数组`dp`包含零并将起始单元格设置为`1`。 这表示当前将机器人留在其初始位置的单个空前缀。 我们不会将此状态添加到答案中，因为禁止使用空程序。 
3. 对每个长度重复过渡`1`通过`l`。 对于每个可遍历的单元格，获取其当前的路径数并将该数字分配给每个有效的相邻单元格。 当邻居的坐标位于网格内并且相应的网格字符不在网格内时，邻居完全有效。`=`。 
4. 更换`dp`与新构建的数组。 这次转变之后，`dp[r][c]`表示以 ((r,c)) 结束的当前长度的有效程序的数量。 保留连续长度的单独数组可以防止转换意外使用同一迭代中较早创建的状态。 
5. 添加`dp[start_row][start_col]`到答案。 这些正是当前长度为迭代次数、最终位置为原始位置的有效程序。 
6. 处理完所有长度后`l`，打印累计答案。 每个非空有效程序都具有 1 到 1 之间的一个长度`l`，因此只计算一次。 

### 为什么它有效

 不变量是在处理完 (k) 个转换后，`dp[r][c]`等于将机器人从起始单元移动到 ((r,c)) 的长度恰好为 (k) 的有效命令序列的数量。 对于 (k=0)，该不变量成立，因为起始单元格处恰好有一个空序列，而其他地方没有。 在转换期间，每个有效的长度（k+1）序列都有一个以某个相邻单元结束的唯一长度（k）前缀，后跟一个有效的移动。 DP 正是添加了这些可能性，并拒绝每一次向墙内或网格外的移动。 因此，该不变量对于每个长度都成立。 尤其，`dp[start]`在 (k) 次移动后，精确计算返回原点的长度为 (k) 的有效程序，并将其对所有正长度求和，准确给出所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, l = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    sr = sc = -1
    for r in range(n):
        for c in range(m):
            if grid[r][c] == '*':
                sr, sc = r, c

    dp = [[0] * m for _ in range(n)]
    dp[sr][sc] = 1

    answer = 0

    directions = ((-1, 0), (1, 0), (0, -1), (0, 1))

    for _ in range(l):
        ndp = [[0] * m for _ in range(n)]

        for r in range(n):
            for c in range(m):
                ways = dp[r][c]
                if ways == 0 or grid[r][c] == '=':
                    continue

                for dr, dc in directions:
                    nr = r + dr
                    nc = c + dc

                    if 0 <= nr < n and 0 <= nc < m:
                        if grid[nr][nc] != '=':
                            ndp[nr][nc] += ways

        dp = ndp
        answer += dp[sr][sc]

    print(answer)

if __name__ == "__main__":
    solve()
```网格首先存储为字符串，因此检查单元格是否是墙很简单`grid[r][c] == '='`。 在阅读网格时，独特的`*`细胞被记录为`(sr, sc)`。 

最初的`dp`数组对应于零个命令。 只有起始位置有一种到达方式。 这种表示很方便，因为相同的转换可以应用于每个命令长度。 

对于每次迭代，`ndp`开始为空。 每个非零状态`dp`表示一些有效前缀的集合。 对于四个方向中的每一个，代码在索引网格之前都会检查新坐标。 这种排序很重要，因为 Python 会引发数组外部坐标的索引错误，否则负索引将引用列表另一侧的单元格。 

条件`grid[nr][nc] != '='`两者都接受`.`和`*`。 机器人可以像任何其他可遍历单元一样穿过起始单元，这对于计算返回路径至关重要。 

仅在生成所有转换后才会替换旧数组。 如果我们更新了`dp`在适当的位置，迭代早期达到的状态可以立即再次使用，从而有效地允许在一个 DP 步骤期间执行多个命令并产生不正确的计数。 

仅在完成转换后才会更新答案。 因此，第一次迭代添加的值表示长度恰好为 1 的程序，而不是空程序。 Python 的任意精度整数也消除了任何溢出问题。 即使命令序列的理论数量大约达到 (10^{18})，Python 也可以准确地表示结果计数。

### 示例 2

 第二个迷宫是```
..=..
..=..
=.*.=
=...=
```机器人有三种可能的二命令返回，即语句中列出的三个长度为二的程序。 还有 19 个长度为 4 的有效返回程序。 奇数个命令不可能返回，因为每次移动都会改变当前单元格的棋盘颜色。 

关键的 DP 值是：

 | 长度 |`dp[start]`| 累计答案 |
 | --- | --- | --- |
 | 0 | 1 | 0 |
 | 1 | 0 | 0 |
 | 2 | 3 | 3 |
 | 3 | 0 | 3 |
 | 4 | 19 | 19 22 | 22

 最终的答案是`22`。 

长度 1 和 3 处的零值展示了网格的二分结构。 移动总是会改变奇偶性`row + column`，因此返回到原始单元格需要偶数次移动。 DP 不需要针对此属性的特殊规则，它自然会为不可能的长度生成零。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O(l \cdot n \cdot m)) | 每次迭代都会扫描每个单元并检查最多四个邻居 |
 | 空间| (O(nm)) | 仅存储当前和下一个 DP 数组 |

 对于 (n,m \le 100) 和 (l \le 30)，最多有 (30 \cdot 100 \cdot 100 = 300{,}000) 个单元状态需要处理，每个状态有四个邻居检查。 由此产生的工作负载完全在 Python 规定的 1 秒限制内，并且两个（100 × 100）整数数组很容易在 128 MB 以内。

 ## 边缘情况

 ### 空程序

 对于```
1 1 1
*
```初始 DP 状态为`dp[0][0] = 1`，但答案从零开始。 唯一的迭代会尝试所有四个方向，并且每个方向都会离开网格，因此下一个 DP 都为零。 最终的答案是`0`。 初始状态用作转换源，而不是其本身作为有效答案。 

### 无效的中间动作

 对于```
1 3 2
=*.
```第一个过渡只能从第 2 列开始移动到第 3 列。左侧邻居是墙，其他两个方向在网格之外。 第一步之后，开始计数为零。 在第二次转换期间，机器人可以从第 3 列移回起点，给出`dp[start] = 1`。 因此答案是`1`。 

无效序列`ЛП`永远不会进入 DP，因为它的第一个过渡目标是墙。 因此，DP 在无效程序失效时拒绝它们。 

### 奇数长度返回

 对于```
2 2 1
*.
..
```第一个转换将机器人发送到其两个邻居之一，但都不是开始。 因此`dp[start] = 0`答案是`0`。 

同样的现象适用于网格图中的每个奇数长度。 每一步都会改变奇偶校验`r + c`，因此奇数次移动无法返回到原始单元格。 该算法不需要单独检测这一点，因为转换计数已经对其进行了编码。 

### 边界单元

 对于```
1 2 4
*.
```机器人从起始单元到右侧只有一次合法的移动。 它必须在第二个命令时向左返回。 唯一可能的返回程序长度可达 4 是`ПЛ`和`ПЛПЛ`，所以答案是`2`。 

边界检查`0 <= nr < n`和`0 <= nc < m`是阻止超出左、右、上、下边缘的移动被计算在内的原因。 

### 多条路径合并到一个单元格中

 对于```
2 2 4
*.
..
```两步后返回有两种方法，一种是向右返回，一种是向下返回。 四次移动后有八个返回程序，总共`10`。 

这正是动态规划节省工作量的情况。 几个不同的前缀可以到达同一个单元格，它们的计数被合并为一个整数`dp[r][c]`。 当选择下一个命令时，所有这些前缀都具有相同的未来选项，因此将它们保留为单个计数不会丢失任何信息。
