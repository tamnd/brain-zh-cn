 ## 解决方案
 ## 问题理解

 该建筑分为入口、楼层和公寓。 每个入口都包含准确的`n`楼层，并且每层楼都包含准确的`m`公寓。 公寓数量从一个入口到下一个入口不断增加：第一个入口包含公寓`1`通过`n*m`，第二个包含下一个`n*m`公寓等。 

我们得到了公寓号码`k`。 任务是确定两件事：包含公寓的入口`k`，以及该入口内包含它的地板。 

例如，与`n = 3`和`m = 4`, 一个入口包含`3 * 4 = 12`公寓。 公寓`1..4`位于公寓 1 楼`5..8`位于2楼，公寓`9..12`位于 3 楼。因此公寓`10`属于3楼1号入口。 

所有三个输入值都可以大到`10^9`。 因此，一个逐一检查公寓、楼层或入口的解决方案可能需要多达约 10 亿次迭代。 在一秒的限制下，这远远超出了我们想要的。 编号的结构给了我们一个直接的算术公式，因此预期的解决方案应该使用恒定的时间和恒定的内存。 

第一个边界情况是当`k`正好可以整除`m`。 例如，`n = 3, m = 4, k = 8`给出输出`1 2`。 8 号公寓是 2 楼的最后一个公寓。粗心的公式如`k / m + 1`会产生第 3 层，因为它忘记了划分必须基于从零开始的位置。 

第二个边界情况是当`k`正好是最后一个公寓的入口。 为了`n = 3, m = 4, k = 12`，正确的输出是`1 3`。 12号公寓仍属于1号入口。使用`k // (n*m) + 1`直接会错误地生成入口 2。 

第三个案例是第一个公寓。 为了`n = 1, m = 1, k = 1`，答案是`1 1`。 任何使用普通除法而不首先移动公寓号的公式都有可能产生从零开始的答案或额外的增量。 

## 方法

 直接的暴力解决方案可以模拟编号。 从公寓 1 开始，我们可以跟踪当前的入口和楼层，每次结束后移动到下一层`m`公寓，每次后前往下一个入口`n`地板。 曾经的公寓`k`到达后，存储的入口和楼层就是答案。 这是有效的，因为它遵循与分配公寓号码完全相同的顺序。 

问题在于迭代次数。 在最坏的情况下，考虑`n = 1`,`m = 1`， 和`k = 10^9`。 每层有一间公寓，因此模拟必须处理所有`10^9`在达到目标之前公寓。 即使使用跳过整个楼层的更有效的模拟，最坏的情况仍然可能需要`10^9`地板或入口过渡。 这不适合一秒的竞争性编程限制。 

关键的观察是每个入口都包含准确的`n*m`公寓。 我们可以直接询问是哪个街区，而不是模拟之前的所有入口`n*m`连续的公寓号码包含`k`。 一旦知道了入口，我们只需要知道`k`那个入口里面。 同样的想法也适用于地板：每层楼都包含精确的`m`公寓，因此入口内的位置决定了整数除法的楼层。 

处理所有边界的最简洁方法是暂时使公寓编号从零开始，方法是考虑`k - 1`。 那么第一间公寓的位置为 0，一楼的最后一间公寓的位置为`m - 1`，第一个入口的最后一个公寓有位置`n*m - 1`。 然后，整数除法和余数与所需的组完全匹配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 最坏情况下的 O(k) | O(1) | O(1) | 太慢了 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算一个入口内的公寓数量：`n * m`。 这给出了全球公寓编号中一个完整入口区块的大小。 
2. 更换`k`和`k - 1`从概念上和计算上`(k - 1) // (n * m) + 1`为入口。 将从零开始的位置除以一个入口块的大小可以告诉我们在目标之前有多少个完整的入口块，并且加一将从零开始的块索引转换为从一开始的入口编号。 
3. 计算`(k - 1) % (n * m)`获取公寓的从零开始的位置`k`在它的入口内。 其余部分丢弃目标之前的所有完整入口。 
4.将该位置除以`m`并添加一个：`(position_inside_entrance // m) + 1`。 每一组`m`连续的位置属于一层，因此商标识从零开始的楼层。 
5. 打印入口号，然后打印楼层号。 

### 为什么它有效

 让`p = k - 1`。 由于每个入口恰好包含`n*m`公寓，商`p // (n*m)`正是公寓之前完整入口的数量`k`。 因此添加一个就给出了正确的入口。 剩下的`p % (n*m)`是公寓在该入口内的从零开始的位置。 由于每层楼都包含准确的`m`公寓，将此余数除以`m`给出公寓之前的完整楼层数，加一给出其从一开始的楼层。 两种计算都使用相同的从零开始的位置，因此楼层和入口末端的公寓被分配到正确的组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m, k = map(int, input().split())

apartments_per_entrance = n * m
position = k - 1

entrance = position // apartments_per_entrance + 1
floor = (position % apartments_per_entrance) // m + 1

print(entrance, floor)
```第一行从唯一的输入行读取三个整数。 该问题没有多个测试用例。`apartments_per_entrance`是一个完整入口区块的大小。 虽然输入值最多是`10^9`，他们的产品可以达到`10^18`。 Python 整数具有任意精度，因此这种乘法是安全的，无需任何特殊处理。`position = k - 1`是核心实施细节。 原始的公寓号是从一开始的，而除法和余数自然描述的是从零开始的组。 移一位就成了公寓`1`位置`0`， 公寓`m`位置`m - 1`，和公寓`m + 1`位置`m`。 这消除了通常的可除性错误。 

入口计算采用整数除以完整入口尺寸。 楼层计算首先取入口内的余数，然后除以`m`。 顺序很重要，因为楼层数仅取决于当前入口内的位置，而不取决于其之前的所有公寓。 

Python 的整数运算还避免了固定宽度 32 位实现可能遇到的溢出`n * m`。 64 位整数在这里也足够了，因为最大乘积为`10^18`。 

## 工作示例

 对于示例 1，输入为`3 4 10`。 每个入口包含`3 * 4 = 12`公寓。 目标是第十间公寓，因此其从零开始的位置是 9。 

|`n`|`m`|`k`| 每个入口的公寓| 零基础岗位| 入口| 入口内的位置 | 楼层|
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 3 | 4 | 10 | 10 12 | 12 9 | 1 | 9 | 3 |

 商`9 // 12`为 0，所以入口为`0 + 1 = 1`。 剩下的`9 % 12`是 9。9 除以 4 得到 2，所以底数是`2 + 1 = 3`。 结果是`1 3`。 

对于示例 2，输入为`5 2 20`。 每个入口包含`5 * 2 = 10`公寓。 公寓 20 具有从零开始的位置 19。 

|`n`|`m`|`k`| 每个入口的公寓| 零基础岗位| 入口| 入口内的位置 | 楼层|
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 5 | 2 | 20 | 20 10 | 10 19 | 19 2 | 9 | 5 |

 商`19 // 10`是 1，给出入口 2。余数是 9，这是该入口的最后一个位置。 由于每层都有两间公寓，`9 // 2`是 4，给出下限 5。结果是`2 5`。

import sys
import io

def solve():
    input = sys.stdin.readline
    n, m, k = map(int, input().split())

    apartments_per_entrance = n * m
    position = k - 1

    entrance = position // apartments_per_entrance + 1
    floor = (position % apartments_per_entrance) // m + 1

    print(entrance, floor)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    result = sys.stdout.getvalue().strip()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

 ## 边缘情况

 当`k`是第一套公寓，零基础位置为零。 用于输入`1 1 1`，入口块包含一间公寓，所以`0 // 1 + 1 = 1`。 入口内的位置也为零，给出`0 // 1 + 1 = 1`。 输出是`1 1`。 

什么时候`k`可以被一层楼的公寓数量整除，目标是上一层，而不是下一层。 用于输入`3 4 8`，从零开始的位置是7。入口是`7 // 12 + 1 = 1`，地板是`7 // 4 + 1 = 2`。 输出是`1 2`。 直接基于公式`k // m`会错误地将 8 号公寓移至 3 楼。 

当`k`恰好是某个入口的最后一个公寓，目标必须留在该入口内。 用于输入`3 4 12`，从零开始的位置是 11。因为`11 // 12 = 0`，入口为 1。入口内的位置为 11，并且`11 // 4 + 1 = 3`，所以输出是`1 3`。 从零开始的偏移使边界表现正确。 

什么时候`k`是入口边界后的第一间公寓，入口必须增加，而楼层重置为 1。对于输入`3 4 13`，从零开始的位置是12。现在`12 // 12 = 1`，所以入口是 2。余数为零，给出楼层`0 // 4 + 1 = 1`。 输出是`2 1`。 

最后，大型产品一定不能引起算术问题。 用于输入`1000000000 1000000000 1000000000`, 一个入口包含`10^18`公寓，而目标只是公寓`10^9`。 其从零开始的位置是`999999999`，仍在第一个入口和一楼内，因为`999999999 // 1000000000 = 0`。 输出是`1 1`。 尽管入口包含大量公寓，但计算是恒定时间。
