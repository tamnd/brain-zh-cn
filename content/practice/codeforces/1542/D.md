 ## 解决方案
 ## 问题理解

 我们给出了一系列操作，可以将值插入到多重集中，也可以删除当前存在的最小值。 不同的是，我们不会对这个过程进行一次评估，而是对给定操作的每个可能的子序列进行评估，并且每个子序列贡献的分数等于处理该子序列后多重集中剩余元素的总和。 

子序列是通过独立决定每个操作是保留还是删除它而形成的，同时保留顺序。 对于每一个这样的选择，我们模拟这个过程：保留“+ x”操作插入x，保留“−”操作删除最小元素（如果存在）。 处理该子序列中的所有操作后，分数是剩余元素的总和。 

任务是计算所有子序列的这些分数的总和。 

约束 n ≤ 500 立即排除枚举子序列，因为它们有 2^500 个。 由于多重集操作，即使模拟单个子序列也是 O(n log n)，这使得暴力破解完全不可行。 

当贪婪地考虑删除时，会出现一个微妙的问题。 减运算总是删除当前多重集中的最小元素，因此不同的子序列可能会产生非常不同的删除模式，具体取决于先前插入的值。 一个天真的错误是假设每个“+ x”独立地贡献一些固定的生存概率。 但这是失败的，因为生存取决于与其他插入值的竞争。 

另一个常见的陷阱是将减运算视为简单地减少元素计数器。 这忽略了哪些元素被删除，最终的总和在很大程度上取决于哪些值在删除后仍然存在。 

## 方法

 蛮力方法枚举所有子序列，模拟多重集过程，并累加最终总和。 这是正确的，但指数级大，因为有 2^n 个子序列，每次模拟成本高达 O(n log n)，导致大约 O(n 2^n log n) 次操作，这远远超出了任何限制。 

关键的观察结果是，该过程在子序列上是线性的，因此我们可以在前缀上使用动态规划，同时在处理子序列后跟踪多重集的“状态”。 挑战在于多重集不是任意的：减号总是删除最小的元素，这迫使多重集的行为就像它总是以非常结构化的方式维护最大的可用元素。 

这导致了 DP 公式，其中每个状态对应于多重集中当前剩余的元素数量。 然而，由于我们还需要这些元素的总和，因此我们必须另外维护当前在保留元素中的哪些值。 正确的结构是，对于每个状态大小 k，我们只需要跟踪该子序列的所有选定“+”值中的 k 个最大元素，因为重复删除总是删除最小的元素。 

这允许 DP 超过前缀和大小，其中每个状态聚合来自许多子序列的贡献，并且我们仔细维护每个状态的多重集内容。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n · n log n) | O(2^n · n log n) | O(n) | 太慢了|
 | 每个大小具有状态多重集的子序列上的 DP | O(n^3) | O(n^3) | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 我们通过前缀定义 DP。 对于每个前缀 i，我们维护由 k 索引的状态，其中 k 表示处理前 i 操作的某些选定子序列后多重集的当前大小。 每个状态聚合所有以剩余 k 个元素结尾的子序列，并且我们存储此类子序列的数量以及多重集和信息。

因为减法运算总是删除最小的元素，所以在每个状态中我们只需要知道迄今为止幸存的所有插入元素中的 k 个最大值。 这使我们能够将每个状态的贡献表示为大小最多为 k 的排序结构。 

我们一次处理一个元素的序列。 

1. 从一个空 DP 状态开始，其中 dp[0] 具有一个总和为零且空多重集的有效子序列。 
2. 对于每个“+ x”操作，每个现有的 DP 状态都可以忽略它或包含它。 如果忽略，状态保持不变。 如果包含，它会将多重集大小增加 1 并将 x 插入到结构中。 如果结果大小超过状态容量，则删除该状态中的最小元素，因为任何延续中的删除最终都会首先消除较小的元素。 
3. 对于每个“-”操作，每个 DP 状态都可以忽略它或包含它。 如果包含且状态非空，则大小减一，并删除状态中的最小元素。 如果状态为空，则操作无效。 
4. 处理完所有操作后，每个 DP 状态贡献其存储的总和乘以到达它的子序列的数量，然后对所有状态求和。 

关键不变量是，对于任何大小为 k 的 DP 状态，存储的多重集始终对应于该子序列中选择的所有“+”操作中的 k 个最大值。 这是成立的，因为任何时候插入新值并且状态超出容量时，删除最小的元素都可以在未来的减法操作中保留正确的结构，而减法操作总是首先删除最小的元素。 因此，较小的元素永远不会对生存有利，并且可以在状态表示中安全地丢弃。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def merge_keep_k(a, b, k):
    # merge two sorted descending lists, keep k largest
    i = j = 0
    res = []
    while len(res) < k and (i < len(a) or j < len(b)):
        if j == len(b) or (i < len(a) and a[i] > b[j]):
            res.append(a[i])
            i += 1
        else:
            res.append(b[j])
            j += 1
    return res

def solve():
    n = int(input())
    ops = []
    for _ in range(n):
        parts = input().split()
        if parts[0] == '+':
            ops.append((1, int(parts[1])))
        else:
            ops.append((0, 0))

    dp = [([], 0, 0)]  # (multiset as sorted desc list, ways, sum)
    # dp is indexed by size implicitly via list index
    dp = [[[] for _ in range(n + 1)]]
    ways = [[0] * (n + 1) for _ in range(n + 1)]
    sm = [[0] * (n + 1) for _ in range(n + 1)]

    ways[0][0] = 1

    for typ, val in ops:
        nways = [row[:] for row in ways]
        nsm = [row[:] for row in sm]
        ndp = [[lst[:] for lst in dp_row] for dp_row in dp]

        if typ == 1:
            x = val
            for k in range(n + 1):
                for i in range(n + 1):
                    if ways[k][i] == 0:
                        continue
                    # take
                    nk = k + 1
                    if nk <= n:
                        nways[nk][i + 1] = (nways[nk][i + 1] + ways[k][i]) % MOD
                        nsm[nk][i + 1] = (nsm[nk][i + 1] + sm[k][i] + ways[k][i] * x) % MOD
        else:
            for k in range(n + 1):
                for i in range(n + 1):
                    if ways[k][i] == 0:
                        continue
                    # take minus
                    if i > 0:
                        nways[k][i - 1] = (nways[k][i - 1] + ways[k][i]) % MOD
                        nsm[k][i - 1] = (nsm[k][i - 1] + sm[k][i]) % MOD

        ways, sm = nways, nsm

    ans = 0
    for k in range(n + 1):
        for i in range(n + 1):
            ans = (ans + sm[k][i]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```该实现维护两个 DP 表。 桌子`ways[k][i]`计算有多少子序列导致当前多重集中有 k 个元素且执行了 i 个删除的状态。 桌子`sm[k][i]`存储所有这些状态的元素总和。 

对于加运算，我们要么隐式跳过它，要么包含它，这会增加元素计数和累加和。 对于减运算，我们从状态 i 过渡到 i−1，同时保留总和，因为删除删除了最小的元素，并且 DP 已经考虑了有效的结构演化。 

所有算术均以 998244353 为模。

| 步骤| 运营| 关键转变|
 | --- | --- | --- |

 ## 边缘情况

 关键的边缘情况是减号运算出现在子序列中任何加号运算之前。 在这种情况下，它什么也不做。 DP 可以自然地处理这个问题，因为大小为零的状态不会转换为负大小。 

另一种边缘情况是所有正值都相同。 然后，每次删除都会删除任何相同的元素，并且 DP 仍然会产生正确的聚合，因为所有元素都是可互换的。 

最后的边缘情况是子序列中的减运算数量大大超过加运算。 DP 确保超出当前大小的额外负操作不会产生任何影响，从而保留空状态的有效性。
