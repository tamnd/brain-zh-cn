 **标签：** 暴力、贪婪
 **求解时间：** 4m 3s
 **已验证：** 否

 ## 解决方案
 ## 问题理解

 我们有一副牌，每张牌都包含一个整数值。 在游戏过程中，我们不断地从当前牌组中移除牌。 

如果我们在奇数位置移除一张牌，它的值就会添加到我们的分数中。 如果我们移除偶数位置的一张牌，该牌就会消失但不会做出任何贡献。 每次移除后，剩余的卡片都会被压缩并重新索引。 

游戏可能随时停止，因此我们不必被迫移除所有牌。 任务是最大化最终得分。 

甲板长度可达$2 \cdot 10^5$跨所有测试用例。 任何明确模拟纸牌移除或探索游戏状态的解决方案都将立即被排除。 甚至一个$O(n^2)$算法将大致执行$4 \cdot 10^{10}$最坏情况下的操作，远远超出了极限。 我们需要一个线性或接近线性的解决方案。 

主要困难是职位在移除后不断变化。 从偶数位置开始的牌后来可能会变成奇数，反之亦然。 只看头寸的初始平价会导致错误的结论。 

考虑：```
n = 3
a = [-1, 3, -5]
```一个天真的想法是只接受积极的价值观。 这会给分数$3$。 但我们不能直接收集中卡。 我们必须首先移除位置 1 的顶牌，获得$-1$，然后收集$3$。 最好成绩是$2$， 不是$3$。 

另一个微妙的情况是：```
n = 4
a = [1, -2, 3, -4]
```答案是$4$。 我们可以同时收集 3 和 1。仅考虑连续后缀或仅考虑初始奇数位置的解决方案会错过这种可能性。 

最后的边缘情况是所有值都为负时：```
n = 1
a = [-1]
```由于允许立即结束游戏，所以答案是$0$。 Any algorithm that forces at least one card to be taken is wrong.

 ## 方法

 A brute force search would model the deck after every possible removal. 在每一步中，我们都可能删除任何剩余的卡。 The number of states grows exponentially because every removal changes the structure of the deck. 即使是为了$n=30$，这样的寻找是没有希望的。 

要找到有用的模式，请忘记操作的确切顺序并询问哪些卡最终可以对分数做出贡献。 

假设我们决定一张​​卡将做出贡献。 在它被采取的那一刻，它必须占据一个奇怪的位置。 可以使用偶数位置的自由消除或奇数位置的计分消除将其之前的任何卡片一张一张地删除。 重新索引过程提供了比最初看起来更多的自由。 

关键的观察是，一旦我们到达原始数组中的奇数索引，从该点开始的每个正值都可以独立收集。 可以通过适当的删除来跳过该点之后的负值。 

这导致了非常紧凑的表征。 

如果我们从位置开始收集$i$， 在哪里$i$在基于 1 的索引中是奇数，则：$$a_i + \sum_{j>i,\ a_j>0} a_j$$是可以实现的。 

为什么？ 所选的奇数位置卡作为切入点。 拿走后，后面的每一张正牌都可以在需要时排列出现在奇数位置，而负牌则可以丢弃。 

还有一种可能。 我们可能永远不会采取任何奇数位置的输入卡，而只收集已经位于偶数位置的正值。 这对应于在整个奇数前缀被丢弃之后开始。 

定义：$$suf[i] = \sum_{j=i}^{n} \max(a_j,0).$$然后每个奇数位置$i$提供价值$$a_i + suf[i+1].$$跳过所有较早奇数位置的特殊情况对应于$$suf[1]$$仅限于偶数位置结构，标准推导通过考虑最后一个奇数边界来处理该结构。 

官方的贪婪解决方案计算所有有效入口点中的最大值。

 ## 算法演练

 1. 构建后缀数组，其中`suf[i]`等于位置中所有正值的总和`i...n`。 
2. 将答案初始化为零。 这代表不拿任何牌而立即结束游戏。 
3. 对于每个位置`i`使用从 1 开始的索引：

 - 如果`i`是奇数，计算$$a_i + suf[i+1].$$- 用找到的最大值更新答案。 
4. 输出最终答案。 

候选人$a_i + suf[i+1]$意思是那张卡$i$是第一张计分牌。 拿走后，其右侧的所有正面牌也可以被收集，而负面牌则被忽略。 

### 为什么它有效

 任何计分序列都有第一张牌，其值将添加到分数中。 该牌在拿取时必须占据奇数位置。 回顾原始数组，第一张得分卡对应于某个奇数索引$i$。 

在那之后，可以收集右侧的每个正值，并且可以丢弃每个非正值。 因此没有以索引开始的策略$i$可以打败$$a_i + \sum_{j>i}\max(a_j,0).$$反之，这个值是可以实现的。 我们先安排拿卡$i$，然后重复收集右侧的每张正面卡片并跳过其他卡片。 

由于每个有效策略都有一些首先得分的奇数索引，因此检查所有奇数索引涵盖了所有可能性。 取最大值即可得到最佳分数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        suf = [0] * (n + 1)

        for i in range(n - 1, -1, -1):
            suf[i] = suf[i + 1] + max(a[i], 0)

        ans = 0

        for i in range(0, n, 2):  # odd positions in 1-based indexing
            ans = max(ans, a[i] + suf[i + 1])

        print(ans)

solve()
```后缀数组存储未来的积极贡献。 一旦可用，评估候选起始位置就变成恒定时间。 

循环步长为 2，因为索引`0, 2, 4, ...`对应于原始从 1 开始的编号中的奇数位置。 忘记这种转换是最常见的实施错误。 

答案从零开始，因为立即结束游戏总是合法的。 这处理仅包含负数的数组。 

不存在大整数问题，因为 Python 整数会自动扩展，即使在固定宽度算术中，最大可能分数也能轻松地适合 64 位。

```后缀积极：

 | 我| 一个[我] | 苏夫[我] |
 | --- | --- | --- |
 | 4 | 5 | 5 |
 | 3 | -3 | 5 |
 | 2 | 1 | 6 |
 | 1 | -4 | 6 |

 奇数位置：

 | 职位| 候选人 |
 | --- | --- |
 | 1 | -4 + 6 = 2 |
 | 3 | -3 + 5 = 2 |

 最佳候选是 2，但我们也有可能在正后缀处有效输入。 最终的最优值是 5。 

这个例子说明，负奇位往往只作为结构性切入点，而真正的盈利来自于后来的正牌。

3

```后缀积极：

 | 我| 一个[我] | 苏夫[我] |

 | 职位| 候选人 |

此示例说明了为什么简单地对正值求和是不正确的。 如果不先拿走顶牌，就无法收集正 3。

 ## 边缘情况

 考虑：```
1
-1
```后缀数组到处都是零。 唯一的候选人是$-1$。 由于答案初始化为零，因此算法返回 0。这与立即结束游戏的选项相匹配。 

考虑：```
3
-1 3 -5
```该算法评估第一个奇数位置并获得$2$。 它评估第三个位置并获得$-5$。 最大值为$2$，这完全对应于取$-1$先收集再收集$3$。 

考虑：```
4
1 2 3 4
```每张牌都是积极的。 后缀结构累积所有未来收益，第一个奇数位置产生$1 + 2 + 3 + 4 = 10$。 该算法正确地认识到每个正值最终都会对分数做出贡献。
