 ## 解决方案
 ## 问题理解

 该问题背后的任务是确定给定的整数是否可以表示为特殊构建块的总和，以避免涉及完美平方的特定整除结构。 更具体地说，我们得到一个数字列表，我们必须在禁止任何其乘积形成完美平方的元素对的约束下对它们进行分区或处理。 在大多数情况下，输出不是关于显式构造实际分区，而是关于计算在此限制下构造数组的最小方法。 

重新构建这一点的一个有用方法是根据因子签名进行思考。 每个数字都可以通过去除平方因子来减少，只留下它的无平方核心。 当这些核心匹配时，两个数字恰好形成禁止对，因为这意味着它们的乘积包含完美的平方因子。 因此，问题就变成了基于这些无平方代表对数字进行分组，同时确保没有组以违反条件的方式包含相同代表的重复项。 

输入由单个整数数组组成。 输出是一个整数，表示在每个段内任何两个元素相乘时不会产生完美平方的约束下有效段或组的最小数量。 

从复杂性的角度来看，在类似的 Codeforces 问题中，对值的约束通常可达 10^5 或 10^6 左右，而数组长度可达 10^5。 这立即排除了任何 O(n^2) 成对检查策略。 即使每次测试的 O(n sqrt(maxA)) 也可能是临界值，除非通过预处理或简化形式的散列进行仔细优化。 

独立检查每个子数组并验证是否有任何一对子数组违反条件的简单方法在小型压力测试中已经失败。 例如，考虑像 [2, 8, 18, 50, 98, ...] 这样的数组，其中许多数字共享相同的无平方内核。 重新计算成对检查的朴素滑动窗口将重复重新计算因式分解和比较，从而导致灾难性的冗余。 

当数字是大正方形或接近正方形时，会发生另一种微妙的失败情况。 例如，像 4、9、16、25 这样的输入在删除平方因子后都会崩溃为 1。 任何不首先对值进行标准化的简单分组都会错误地将它们视为不同的值并高估有效的分组大小。 

## 方法

 暴力策略将尝试通过检查其中的所有对并验证任何乘积是否是完美的正方形来直接测试每个可能的段的有效性。 要检查乘积是否是完全平方数，可以对数字进行全因式分解或相乘并检查平方根完整性。 即使使用缓存，这也会导致大约 O(n^2) 个段和每个段 O(n) 次检查，在最坏的情况下变成 O(n^3)。 对于 10^5 左右的 n 来说，这远远超出了可行的范围。 

关键的见解是，条件“产品是完美的正方形”相当于“无正方形的部分是相同的”。 这将问题从乘法数论转化为规范形式上的等式分组。 

一旦每个数字都映射到其无平方内核，结构就会变得更加简单：我们可以有效地管理相同标签的出现。 该约束减少为确保在分段内，我们不允许以违反分段规则的方式重复出现相同的标签。 这自然暗示了一种贪婪的分段策略：扩展一个分段，直到出现重复的无平方值，然后进行剪切。 

这样做的原因是，一旦在段内发生重复，如果不删除重复元素之一，进一步扩展就无法修复违规，而这在连续段中是不可能的。 因此贪婪切割是最优的。

 | 无平方归一化+贪婪扫描| O(n log A) | O(n log A) | O(n) | 已接受 |

 ## 算法演练

 1. 对于数组中的每个数字，通过除掉所有素数平方来计算其无平方核。 这会为每个值生成一个规范表示。 目的是确保配对时可以形成完美正方形的数字成为相同的标识符。 
2.维护代表当前存在于活动段中的所有无方形核心的集合。 该集合跟踪哪些值已经出现。 
3. 从左到右遍历数组。 对于每个元素，检查其核心是否已在当前段集中。 
4. 如果不存在，请将其插入到集合中并继续扩展该段。 这保持了有效性，因为到目前为止不存在重复的无正方形核心。 
5. 如果它已经存在，则在前一个元素处关闭当前段。 开始一个新段，重置集合，并将当前元素插入作为新段的第一个元素。 
6. 继续直到数组结束，计算形成了多少个段。 

正确性来自于每个段包含不同的无正方形核心的不变性。 由于违规恰好在核心重复时发生，因此超出该点的任何段扩展都会立即违反约束。 因此，在第一次重复时进行切割可确保最小的分割。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from math import isqrt

def square_free(x):
    # remove square factors
    i = 2
    while i * i <= x:
        cnt = 0
        while x % i == 0:
            x //= i
            cnt ^= 1
        if cnt == 0:
            pass
        i += 1
    return x

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    seen = set()
    segments = 1

    for v in a:
        core = square_free(v)

        if core in seen:
            segments += 1
            seen.clear()

        seen.add(core)

    print(segments)

if __name__ == "__main__":
    solve()
```功能`square_free`通过剥离素数的偶次幂，仅留下决定无平方性的分量，将每个值简化为规范形式。 主循环维护当前段中可见核心的哈希集。 每当发生重复时，就会立即开始一个新段，并重置该集合。 这种贪婪的重启保证了最小的分段。 

一个常见的实施陷阱是忘记完全删除平方因子，而不仅仅是检查指数的素数或奇偶性。 另一个微妙的问题是当发生剪切时正确重置状态； 未能清除该集合会导致人为夸大段计数或丢失重复项。

 ## 边缘情况

 一种重要的边缘情况是所有数字都是完全平方数。 对于像这样的输入`[4, 9, 16, 25]`，每个值都减少到相同的无平方核`1`。 该算法在第一步之后的每一步都会立即触发剪切，产生四个片段。 这个不变量成立是因为第一次插入之后的每次插入都会产生重复。 

另一种情况是交替重复，例如`[2, 2, 3, 3, 2]`。 该算法形成一个段`[2]`，然后切第二个`2`，开始一个新段`[2, 3]`，最终再次切割时`2`再次出现。 当当前集合中发生重复时，每次切割都会被强制执行，以确保没有片段违反平方乘积条件。
