 ## 解决方案
 ## 问题理解

 我们得到一棵树，其中每条边都带有一个整数值。 树是固定的，但边缘值随时间变化。 系统支持两种操作。 

第一个操作选择两个节点和一个值 z，然后通过与 z 应用按位异或来修改位于这两个节点之间的唯一简单路径上的每条边的值。 这不是替换，而是二进制表示形式的切换，独立应用于该路径上的每个边。 

第二个操作要求单个节点，并需要计算当前关联到该节点的所有边值的异或。 

该树最多有 500,000 个节点，操作数量也最多 500,000 个，因此任何显式检查路径上每条边的解决方案都会失败。 即使单个长路径更新也可以触及 O(n) 条边，并且在 q 个操作中重复该操作会导致 O(nq)，这远远超出了可行的限制。 

一个微妙的点是，更新不要求路径和或路径查询，而是修改边缘状态，并且查询对于节点来说是本地的，但依赖于所有相邻的边缘。 这种不匹配是天真的遍历方法失败的地方。 

当重复更新链状树中的长路径时，会出现典型的失败情况。 例如，在 100000 个节点的链中，从一端到另一端的单个更新将触及几乎每条边，并且重复执行此操作会立即超出时间限制。 

## 方法

 直接模拟方法将通过使用 DFS 或 BFS 查找 x 和 y 之间的路径来重新计算每条路径，然后迭代该路径上的所有边并切换它们的值。 这在概念上很简单，因为树结构保证了唯一的路径。 然而，在最坏的情况下，每个这样的操作都可能花费线性时间。 对于 500,000 次操作，这变得不可行。 

关键的观察结果是，虽然边正在更新，但查询并不是询问路径或子树，而只是询问与节点相关的边的异或。 这使我们能够避免在更新后显式跟踪每条边。 

考虑当单条边 (u, v) 的值与 z 进行异或时会发生什么。 该更改恰好影响两个节点：u 和 v，因为两个端点都在其邻接列表中看到该边。 如果我们从节点贡献的角度考虑，则每个边更新都相当于对该边的两个端点应用 XOR z。 

现在考虑从 x 到 y 的完整路径更新。 该路径由一系列边组成。 路径上的每个内部节点恰好与这些更新的边中的两条相关联，而端点 x 和 y 恰好与其中一条相关联。 由于 XOR 是其自身的逆，因此应用 z 两次会抵消。 因此，内部节点接收到的净效应为零，而端点接收到的恰好是一个 XOR z。 

这将整个路径更新压缩为常数时间操作：我们只需要将 z 异或为 x 和 y。 

我们还为每个节点维护初始关联边权重的异或。 每次更新都会为端点提供额外的切换。 查询只是将初始值与所有累积的切换相结合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每次更新的暴力路径遍历 | O(nq) | O(n) | 太慢了 |
 | 端点切换聚合| O(n + q) | O(n) | 已接受 |

 ## 算法演练

 我们将树植根于任何地方，尽管植根实际上并不是正确性所必需的。 我们首先计算每个节点的所有关联边权重的初始异或。 

每条边都将其权重贡献给它的两个端点，因此我们可以初始化一个数组`base[x]`直接存储这个异或。 

我们还维护另一个数组`delta[x]`，最初全为零，存储所有路径更新的累积效果。 

现在我们按顺序处理操作。 

1. 对于节点 x 和 y 以及值 z 的类型 1 操作，我们应用`delta[x] ^= z`和`delta[y] ^= z`。 这代表了这样一个事实：路径的端点恰好经历了 z 的净异或效应。 
2. 对于节点 x 的类型 2 操作，我们输出`base[x] ^ delta[x]`。 这将原始事件 XOR 与通过路径更新影响与 x 相关的边的所有修改相结合。 

步骤 1 的正确性依赖于计算节点 x 作为路径上更新边的端点出现的次数。 内部节点出现两次并取消，端点出现一次并保留。 

### 为什么它有效

 每个边缘更新都会影响其两个端点。 路径更新是沿简单路径的边缘更新的集合。 对于任何节点，该路径中的事件更新边的数量可以是零、一或二，具体取决于它是在路径外部、路径端点还是路径上的内部节点。 XOR 累加将“两次出现”的情况变为无变化，将“一次出现”的情况变为单次切换。 这将整个路径结构减少为仅限端点的效果，保留每个节点应从所有修改的边接收的确切贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, q = map(int, input().split())

    base = [0] * (n + 1)
    delta = [0] * (n + 1)

    edges = []

    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        base[u] ^= w
        base[v] ^= w
        edges.append((u, v, w))

    out = []

    for _ in range(q):
        tmp = input().split()
        op = int(tmp[0])

        if op == 1:
            x = int(tmp[1])
            y = int(tmp[2])
            z = int(tmp[3])

            delta[x] ^= z
            delta[y] ^= z

        else:
            x = int(tmp[1])
            out.append(str(base[x] ^ delta[x]))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```实现预先计算`base[x]`通过在读取边缘时直接对所有入射边缘权重进行异或。 这避免了存储邻接列表。 这`delta`数组累积了接触每个端点的所有路径更新的效果。 

对于类型 1 操作，仅更新两个端点。 这是消除对路径长度依赖的关键优化。 

对于类型 2 操作，答案是所有关联边的当前有效 XOR，重构为原始值加上所有累积的端点切换。 

## 工作示例

 考虑一个小链：

 输入：```
3 3
1 2 1
1 3 2
2 1
1 1 3 2
2 1
```我们从构建开始`base`：

 节点 1 具有边 (1,2)=1 和 (1,3)=2，因此 base[1]=3。 

节点 2 的基数[2]=1。 

节点 3 的基数[3]=2。 

最初 delta 全部为零。 

| 步骤| 运营| 增量[1] | 增量[2] | 德尔塔[3] | 查询结果 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 查询 1 | 0 | 0 | 0 | 基数[1]=3 |
 | 2 | 用 z=2 更新 1-3 | 2 | 0 | 2 | - |
 | 3 | 查询 1 | 2 | 0 | 2 | 3 ^ 2 = 1 | 3 ^ 2 = 1

 第二步仅将 XOR 2 应用于节点 1 和 3，这反映了仅路径更新的端点受到影响。 

该跟踪显示了如何隐式处理内部边缘而无需显式处理。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |

 | 空间| O(n) | 基数和增量的数组 |

 ## 边缘情况

 一个关键的边缘情况是更新路径退化为单个节点，即 x 等于 y。 在这种情况下，没有边缘受到影响，因此操作不得改变任何内容。 该算法可以正确处理这个问题，因为它适用`delta[x] ^= z`两次，一次用于 x，一次用于 y，并且由于它们是同一节点，因此 XOR 抵消。 

另一种情况是星形树，其中许多更新都针对中心节点。 由于叶子之间的每条路径都经过中心，因此看起来中心应该进行大量更新。 实际上，端点规则确保每次操作仅切换叶子，并且中心保持稳定，除非它是端点。 

第三种情况是在同一路径上重复相同的更新。 因为 XOR 是其自身的逆，所以两次应用相同的更新会完全抵消。 这`delta`累积自然地保留了此属性，因为每次更新都会独立切换端点，并且重复切换会恢复状态。
