 ## 解决方案
 ## 问题理解

 我们在堆栈上生成操作序列，以递增顺序处理从 1 到 n 的数字。 在任何时候，我们要么取出下一个未使用的数字并将其压入堆栈，要么将当前堆栈顶部（如果它不为空）弹出。 每次入栈都会将入栈的值作为正数附加到序列 Q 中，每次弹出都会将弹出的值作为负数附加到序列 Q 中。 

由于入栈必须遵循 1、2、3、...、n 的顺序，因此唯一的自由是在标准堆栈有效性规则下交错入栈和出栈。 每个数字都被压入一次并弹出一次，因此 Q 的长度始终为 2n 并包含每个值 i 两次，一次为正，一次为负。 

目标是计算有多少个这样的有效操作序列产生了“k-good”的 Q。 如果 Q 内部某处存在至少 k 个连续负值的连续块，则序列是 k 好序列。 由于负值恰好在我们弹出时出现，因此这种情况相当于在操作序列中运行了至少 k 个连续的弹出操作。 

因此，问题简化为计算有效的堆栈操作序列（类似 Dyck 的序列），其中至少一段连续弹出的长度至少为 k。 

约束 n ≤ 3000 意味着任何比大约 O(n^2) 或 O(n^2 log n) 更差的解决方案都有可能太慢。 除非仔细控制，否则涉及堆叠高度和游程长度的状态上的立方 DP 将太大。 

当 k = 1 时，会出现微妙的边缘情况。在这种情况下，任何单个弹出都已形成有效的运行，因此每个有效的堆栈序列都自动为 k-good。 另一个边缘情况是 k = n，我们本质上是在问是否存在所有剩余元素被连续弹出的时刻，这种情况仅发生在完全递减的弹出序列中。 

## 方法

 操作序列恰好是长度为 2n 的 Dyck 路径：push 对应于向上步骤，pop 对应于向下步骤，并且约束条件是我们在任何时候弹出的内容都不会超过我们推送的内容。 每个有效序列都唯一对应于一个加泰罗尼亚语结构。 

暴力方法将生成所有有效的 Dyck 序列并模拟连续弹出的任何运行是否达到长度 k。 这种序列的数量是第 n 个加泰罗尼亚数，呈指数增长。 即使 n = 20 这也是不可行的，因此枚举是不可能的。 

关键的观察是，我们不需要知道全局的整个序列结构，只需要知道我们是否已经创建了足够长的连续弹出运行。 这是一个局部属性，仅取决于构造过程的当前状态：已推送多少个元素、已弹出多少个元素以及当前连续弹出条纹有多长。 

这自然会导致前缀状态上的动态编程。 我们跟踪有多少数字已被推送，有多少数字已弹出，以及最后一个连续弹出段的当前长度。 每次转换都会重置此连续记录（在推送时）或增加它（在弹出时），同时尊重堆栈有效性。 

我们计算所有有效序列，然后减去那些从未达到长度 k 的流行条纹的序列。 这避免了在构建期间显式检测不良事件，而是通过状态限制来强制执行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 所有有效序列的暴力枚举 | O(C_n) | O(C_n) | O(n) | 太慢了 |
 | 具有（推、弹出、弹出连续）状态的 DP | O(n^2k) | O(n^2k) | O(n^2k) | O(n^2k) | 已接受 |

 ## 算法演练

我们定义一个 DP 状态 dp[i][j][t] 为有效操作序列的数量，其中 i 个数字已被压入，j 个数字已被弹出，并且当前连续弹出条长度恰好为 t。 仅当最后一次操作是弹出操作时，t 值才有意义； 按下后它变成0。 

我们只允许 j ≤ i 的状态，因为我们不能从空堆栈中弹出。 

我们将 t 限制为 k − 1，因为一旦我们达到 k 个连续弹出，我们就认为该序列“坏”并将其从 DP 中排除。 

### 步骤

 1. 初始化dp[0][0][0] = 1，代表一个空序列，没有任何操作，也没有pop streak。 
2. 从任何状态 dp[i][j][t] 开始，如果 i < n，则考虑添加推送操作。 这会转换为 dp[i+1][j][0]，因为按下会将连续弹出条纹重置为零。 推送始终有效，因为我们按固定顺序推送。 
3. 从任何状态 dp[i][j][t] 开始，如果 j < i，则考虑添加弹出操作。 仅当堆栈非空时才有效。 如果 t + 1 < k，则转换将转到 dp[i][j+1][t+1]，因为达到 k 个连续弹出将违反约束。 
4. 以 i 和 j 的递增顺序迭代状态，以便所有转换都在其源之后进行处理。 
5. 填充所有状态后，对从 0 到 k − 1 的所有 t 求和 dp[n][n][t]，以获得没有连续 k 个弹出的有效序列的数量。 
6. 从有效堆栈序列的总数中减去该结果，该总数是通过 DP 或组合数学计算的第 n 个加泰罗尼亚数。 

一个更简单、更清晰的变体通过仅在有效状态上定义 DP 并直接计算 dp[n][n][t] 并对它们求和，完全避免了 Catalan 减法； 这已经准确计算了避免 k 个连续弹出的序列。 由于该问题要求 k-good 序列，因此我们从 Catalan 总数中减去。 

### 为什么它有效

 DP 状态完全捕获扩展部分序列所需的所有信息：压入次数决定哪些值可用，弹出次数决定堆栈高度，而条纹长度决定我们是否已经违反了约束。 未来的决策不依赖于这三个值之外的早期结构。 每个有效序列都通过唯一的转换构造一次，因此 DP 既完整又不重叠。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def catalan(n):
    # C_n = (1/(n+1)) * binom(2n, n)
    fact = [1] * (2*n + 1)
    inv = [1] * (2*n + 1)
    for i in range(1, 2*n + 1):
        fact[i] = fact[i-1] * i % MOD
    inv[2*n] = pow(fact[2*n], MOD-2, MOD)
    for i in range(2*n, 0, -1):
        inv[i-1] = inv[i] * i % MOD

    def C(n, r):
        return fact[n] * inv[r] % MOD * inv[n-r] % MOD

    return C(2*n, n) * pow(n+1, MOD-2, MOD) % MOD

def solve():
    n, k = map(int, input().split())

    # dp[i][j][t]
    dp = [[[0] * k for _ in range(n+1)] for _ in range(n+1)]
    dp[0][0][0] = 1

    for i in range(n + 1):
        for j in range(i + 1):
            for t in range(k):
                val = dp[i][j][t]
                if not val:
                    continue

                # push
                if i < n:
                    dp[i+1][j][0] = (dp[i+1][j][0] + val) % MOD

                # pop
                if j < i and t + 1 < k:
                    dp[i][j+1][t+1] = (dp[i][j+1][t+1] + val) % MOD

    no_bad = 0
    for t in range(k):
        no_bad = (no_bad + dp[n][n][t]) % MOD

    total = catalan(n)
    print((total - no_bad) % MOD)

if __name__ == "__main__":
    solve()
```实现直接遵循 DP 状态。 三维表对前缀决策进行编码：i 跟踪已推送的值数量，j 跟踪已弹出的值数量，t 跟踪当前连续弹出运行长度。 推送转换总是将 t 重置为零，因为任何推送都会中断连续的弹出条纹。 弹出转换会递增 t，并且仅当堆栈非空且未超过连续限制时才允许。 

Catalan 计算给出有效堆栈序列的总数，减去从未达到长度 k 的序列数。 

## 工作示例

 考虑 n = 3 和 k = 2 的样本。由于 DP 很大，我们仅在概念上跟踪状态，但关键行为是任何单个弹出都已经违反了“无 k 连续弹出”条件。 因此，我们正在计算没有两次连续弹出的序列，并从所有加泰罗尼亚序列中减去它们。 

第二个说明性情况是 n = 3，k = 3。这里我们只排除包含三个连续弹出的序列，这种情况仅发生在所有推送之后完全递减的弹出顺序中。 DP 允许所有其他交织，因此只有一个序列从 Catalan 总数中排除。

 ## 边缘情况

 当 k = 1 时，每个有效的堆栈序列都会自动成为 k-good，因为任何弹出操作都已形成长度为 1 的连续负段。 DP 仍然计算没有违反约束的序列数，并且减法留下完整的加泰罗尼亚语计数，与预期行为相匹配。 

当 k = n 时，唯一禁止的模式是连续发生的完整弹出序列。 DP 自然允许所有其他交错，并且只有完全降序的弹出顺序才有助于长度为 n 的游程，因此它从总数中仅排除一次。 

当n=1时，只有1次push和1次pop。 DP 恰好有两个有效状态，并且单个序列始终包含长度为 1 的弹出游程，这与 k = 1 时的 k-good 匹配，否则不匹配。
