 ## 解决方案
 ## 问题理解

 我们得到一个目标小写字符串和一个最初为空的工作区。 目标是在非常特定的工具集下使用尽可能少的操作来构造字符串：我们可以将单个字符附加到当前文本的末尾，我们可以将整个当前文本复制到剪贴板中（替换其中的任何内容），并且我们可以将剪贴板内容粘贴到当前文本的末尾。 

关键的困难在于复制始终是当前文本的“完整快照”，而不是子字符串，而粘贴总是附加整个剪贴板。 这意味着利用重复的唯一方法是首先构建一些前缀，复制它，然后重复粘贴相同的前缀。 

输出只是将空字符串转换为给定目标字符串所需的最少操作数。 

字符串长度最多可达 100,000 的限制立即排除了任何尝试模拟所有可能的操作序列的解决方案。 对“当前字符串+剪贴板”的简单状态搜索将会爆炸，因为两个维度都线性增长并且分支是恒定的。 即使是在没有优化的情况下比较所有子串的动态编程也会由于重复的子串检查而降级为二次或三次行为。 

当重复与单字符扩展不对齐时，就会出现天真的贪婪思维的微妙失败案例。 

例如，考虑一个像这样的字符串`ababab`。 贪婪的构建器可能会插入字符，直到`abab`，复制粘贴一次即可得到`ababab`，使用相对较少的操作。 但对于像这样的字符串`aaabaaa`，过早的贪婪复制是有害的，因为复制不稳定的前缀会阻止以后重用更好的重复结构。 

另一个陷阱是假设我们应该尽早复制。 为了`aaaaa`, 构建后复制`a`看起来很诱人，但构建后复制`aaa`严格来说更好，因为它减少了后续操作。 

这些交互表明，最佳策略取决于识别前缀何时可以准确地平铺更大的前缀。 

## 方法

 蛮力的想法是将每个状态视为由当前构建的字符串和剪贴板内容组成的对。 从每个状态，我们尝试所有三个操作。 这形成了节点为字符串的图中的最短路径问题。 即使将我们限制为目标字符串的前缀，剪贴板的可能性也呈指数级增长，并且状态之间的转换仍然需要比较长字符串。 可到达状态的数量远远超出了实际限制，长度可达 100,000。 

失败点在于状态空间不仅与字符串长度呈线性关系，而且还取决于所有先前复制的段。 

关键的观察是，剪贴板仅在复制时包含等于整个当前前缀的字符串时才有用。 复制长度为 j 的前缀后，每次粘贴都会将字符串精确扩展 j 个字符，这意味着我们只能从该点达到 j 倍数的长度。 

这将问题转化为将字符串结构化分解为块。 如果一个长度为i的前缀可以被分割成k个相同的长度为j的块，那么我们可以通过首先构造长度为j的前缀，复制一次，然后粘贴k−1次来构建它。 这需要 dp[j] 加上该段的 k 次操作。 

除此之外，我们总是有一个接一个插入字符的后备方案。 

因此，最佳解决方案是对前缀长度进行动态编程，并通过可分性检查和快速子串相等性测试进行丰富。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力状态搜索 | 指数| 指数| 太慢了 |
 | 具有块分解的 DP | O(n √n) | O(n √n) | O(n) | 已接受 |

 ## 算法演练

 我们将 dp[i] 定义为构造目标字符串的前 i 个字符所需的最少操作数。 

### 步骤

 1. 初始化 dp[0] = 0，因为空字符串不需要任何操作。 
2. 对于从 1 到 n 的每个位置 i，从基线转换 dp[i] = dp[i − 1] + 1 开始。这对应于直接插入第 i 个字符。 无论结构如何，这始终有效。 
3. 对于每个 i，考虑所有可能的块大小 j，使得 j 整除 i。 我们测试长度 i 的前缀是否由长度 j 的前缀的重复副本组成。 
4. 为了有效地验证重复，我们检查所有 k 的 s[0:j] 是否等于 s[k·j:(k+1)·j]。 这是使用滚动哈希来实现的，因此每次检查的时间复杂度为 O(1)，避免了重复的子字符串扫描。 
5. 如果前缀是长度为 j 的有效重复，重复 k = i / j 次，那么我们可以通过以下方式达到长度 i：

 构建 dp[j],

 复制一次（1次操作），

 粘贴 k − 1 次。 

这贡献了候选值 dp[j] + k。 
6. 取所有有效 j 和插入基线的最小值。 

关键的决策点是我们只允许在边界处进行复制操作，从而在最终前缀中生成精确的周期结构。 这避免了考虑无效的剪贴板状态。 

### 为什么它有效

 任何最佳构造都可以被视为一系列阶段。 每个阶段要么附加一个字符，要么复制一个已经构建的前缀并通过粘贴重复它。 每当使用副本时，剪贴板内容等于当时完全构造的某个前缀，并且所有后续操作都通过重复该确切块来扩展字符串。 因此，使用粘贴操作创建的任何段都必须是已构造的前缀的完美重复。 DP 准确地列举了这些可能性，确保每个有效的构造都是可表示的，而插入过渡则确保我们永远不会错过非重复增长。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def build_hash(s):
    n = len(s)
    base = 91138233
    mod = 972663749
    pref = [0] * (n + 1)
    p = [1] * (n + 1)

    for i, c in enumerate(s):
        pref[i + 1] = (pref[i] * base + (ord(c) - 96)) % mod
        p[i + 1] = (p[i] * base) % mod

    return pref, p, mod

def get_hash(pref, p, mod, l, r):
    return (pref[r] - pref[l] * p[r - l]) % mod

def solve():
    s = input().strip()
    n = len(s)

    pref, p, mod = build_hash(s)

    def equal(a, b, length):
        return get_hash(pref, p, mod, a, a + length) == get_hash(pref, p, mod, b, b + length)

    dp = [10**18] * (n + 1)
    dp[0] = 0

    for i in range(1, n + 1):
        dp[i] = dp[i - 1] + 1

        j = 1
        while j * j <= i:
            if i % j == 0:
                for d in (j, i // j):
                    if d == i:
                        continue
                    k = i // d
                    ok = True
                    for t in range(k):
                        if not equal(0, t * d, d):
                            ok = False
                            break
                    if ok:
                        dp[i] = min(dp[i], dp[d] + k)
            j += 1

    print(dp[n])

if __name__ == "__main__":
    solve()
```该解决方案是围绕前缀动态规划构建的。 插入的 DP 转换非常简单，并确保我们始终有一个有效的后备。 

更微妙的部分是重复检查。 对于每个候选块大小，我们验证前缀是否是完全周期性的。 这可以避免错误地假设局部匹配意味着全局重复。 散列的使用确保子字符串比较的时间恒定，这是至关重要的，因为直接比较会使每次检查的解决方案呈二次方。 

除法循环仅考虑 i 的因素，这使得候选者的数量足够小以适应时间限制。

 ## 边缘情况

 像这样的单字符字符串`a`已正确处理，因为 dp[1] 是从 dp[0] + 1 初始化的，并且不应用复制转换。 

完全统一的字符串，例如`aaaaaa`触发多个有效除数检查。 当 i = 6 时，算法正确识别长度 3 或 2 或 1 可以平铺前缀，并选择 dp[j] + i/j 中最好的一个，从而比纯插入显着减少。 

不重复的字符串，例如`abcdef`永远不会满足任何大于 1 的除数 j 的定期检查，因此 DP 退化为纯插入，这是正确的行为，因为复制粘贴没有提供任何好处。 

像这样的边界情况`ababab`证明了全前缀定期验证的重要性。 仅检查本地匹配会错误地允许无效转换，但完整的哈希验证通过强制每个块完全匹配来确保正确性。
