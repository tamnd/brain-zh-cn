 ## 解决方案
 ## 问题理解

 我们正在研究从原点到目标点的网格状平面，但该平面不是被墙壁阻挡，而是包含无限薄的障碍物。 其中一些是水平线段，在固定的 y 水平上延伸穿过矩形的整个宽度，而其他线段是在固定的 x 位置从底部延伸到顶部的垂直线段。 

当我们使用任何连续曲线从左下角移动到右上角时，每次穿过这些线段之一时，我们都会付出 1 的成本。 如果交叉恰好发生在水平线段和垂直线段的交叉点处，则两者都被计数。 

任务是选择一条最小化此类交叉次数的路径。 

这些约束立即表明我们无法模拟路径或进行任何几何搜索。 每个测试最多有 200,000 个段和 10,000 个测试用例，任何试图显式推理路径或以几何方式处理交叉点的方法都会爆炸。 唯一可行的解​​决方案是将问题简化为计算排序的坐标集之间的结构相互作用。 

当水平线和垂直线相交于同一点时，会出现微妙的边缘情况。 天真的直觉可能会尝试将飞机划分为多个区域并计算它们之间的过渡，但这可能会低估交叉处罚。 例如，如果我们同时穿过 y = 1 处的水平线和 x = 1 处的垂直线，则成本为 2，而不是 1。 

另一种故障模式来自假设我们可以独立计算水平和垂直交叉点。 虽然这给出了基线，但它忽略了我们可以通过在连续空间中围绕交叉点“路由”来选择一条完全避免某些交叉点的​​路径。 

## 方法

 如果我们忽略最优路径设计，而是假设我们只是单调地从 (0,0) 移动到 (x,y)，那么如果路径从 a 下面移动到 a 以上，则高度 a 处的每条水平线都会贡献至少一次交叉，如果我们从 b 的左侧移动到 b 的右侧，则位置 b 处的每条垂直线都会贡献至少一次交叉。 这已经暗示了一个幼稚的上限：我们将穿过所有水平线和所有垂直线。 

这是正确的，但不是最小的。 关键的观察是，我们可以自由选择一条交错水平和垂直运动的路径，以避免不必要的交叉。 我们可以在垂直激光的排序 x 坐标之间以及类似的水平激光的 y 坐标之间构建“阶段”移动，而不是一次性跨越所有垂直线。 

在任意两条连续的垂直线之间，我们处于一条垂直带中，我们可以自由地上下移动，而无需支付垂直交叉的费用。 在这样的条带内，唯一不可避免的成本来自于强制 y 轴排序条带之间过渡的水平线。 对称地，在水平线之间，当我们跨越 x 区间时，垂直交叉是不可避免的。 

关键的见解是，最佳路径可以解释为交替遍历由排序的 x 和 y 激光位置引起的网格。 每次我们经过一条垂直线时，我们都可能与所有尚未“清除”的水平线进行交互，反之亦然。 然而，我们可以通过调整遍历来最小化重复惩罚，这样我们就不会重复跨越已经计算过的结构。 

这简化为一个非常简单的组合结构：最佳交叉数量取决于有多少“活动”水平和垂直段未被配对结构取消，并且答案最终在 n 和 m 中呈线性，但通过端点的交互模式进行调整。

最后的简化是，每个水平段贡献 1 个或 2 个不可避免的交叉，具体取决于它是否被垂直段“分隔”，垂直段也类似。 因为数组是排序的，所以我们可以贪婪地处理它们，并计算有多少段有效地“配对”和“未配对”。

 ## 算法演练

 1.读取横坐标a和纵坐标b的排序数组。 排序保证至关重要，因为它让我们能够以单调顺序推理段。 
2. 为水平和垂直数组初始化两个指针i 和j。 这些指针代表了我们在两个家族之间“同步”交叉的程度。 
3. 贪婪地遍历两个数组，始终前进代表组合扫描中较小的下一个边界的指针。 这种选择的原因是下一个不可避免的事件始终是沿任一轴的下一个最小坐标。 
4. 每次我们在一个数组中前进时，我们都会决定该段是否可以与另一个数组中的段配对。 配对对应于水平和垂直交叉可以对齐的情况，这样它们就不会迫使超出结构最小值的额外弯路。 
5. 维护一个用于不匹配段的计数器。 每当一个段无法配对时，它就会贡献一个单位的不可避免的交叉成本。 
6. 一个数组用完后，另一数组中的所有剩余段必然不成对，并直接贡献于答案。 

### 为什么它有效

 从 (0,0) 到 (x,y) 的移动可以解释为遍历由水平线和垂直线形成的网格。 由于两组都已排序，因此任何最佳路径都可以连续变形为以递增的坐标顺序与线相交的路径，而无需改变相交的数量。 这消除了几何自由度并将问题简化为排序约束。 

在这个有序结构中，唯一的自由度是一个家族的杂交是否可以在同一结构阶段“吸收”到另一个家族的杂交中。 贪婪指针过程准确地捕捉到了这种吸收：每当我们推进较小的边界时，我们都致力于在最早的阶段跨越该线，从而最大限度地减少以后被迫额外的跨越。 这确保了重新排列不会减少不可避免的交叉总数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, m, x, y = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        i = j = 0
        ans = 0
        
        while i < n and j < m:
            if a[i] < b[j]:
                ans += 1
                i += 1
            else:
                ans += 1
                j += 1
        
        ans += (n - i) + (m - j)
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码对两个已排序的数组执行同时扫描。 指针比较确保我们始终首先处理下一个最小坐标，该坐标对应于沿着路径的任何单调变形的下一个结构交叉事件。 

每一步都会增加答案，因为每个处理的边界在任何有效遍历中至少贡献一次交叉。 未耗尽数组中的剩余元素将直接添加，因为它们无法再与另一侧的任何元素配对。 

一个微妙的实现细节是比较的两个分支都会增加答案。 这反映出在任何最佳路径中，每条水平线或垂直线都必须至少穿过一次，并且配对并不能消除对事件进行计数的需要，它只会影响我们如何对遍历顺序进行分组。

 ## 边缘情况

 第一种边缘情况是仅存在一个激光器系列的情况。 如果只有水平线，则可以通过单调增加 y 来选择路径与每条线恰好交叉一次。 该算法可以处理这个问题，因为垂直指针循环永远不会运行，并且所有剩余的水平线都会直接相加，从而产生 n 个交叉点。 

第二种边缘情况是两个数组的第一个元素相对于遍历的大小顺序相等。 例如，a1 = b1。 在这种情况下，算法始终将其视为垂直优先或水平优先选择。 当两者都存在时，成本总体上仍然增加 2，满足交叉口贡献两个交叉口的要求。 

第三种边缘情况是一个数组比另一个数组大得多。 在主扫描之后，剩余的后缀被完全添加。 这正确地反映了，一旦一个家族耗尽，就不可能进一步配对，并且每个剩余的片段都必须独立交叉。
