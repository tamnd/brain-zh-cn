 ## 解决方案
 ## 问题理解

 问题给了我们一个数字`x`和一个长度`n`并要求我们通过交替构建一个序列`x`和`-x`，开始于`x`。 然后我们被要求计算该序列中所有元素的总和。 从概念上讲，这就像翻转符号`x`每一步并将值相加。 

例如，如果`x = 2`和`n = 5`，序列是`2, -2, 2, -2, 2`。 总结这些给出`2`。 如果`n = 4`，序列`2, -2, 2, -2`总和为`0`。 

限制非常小：两者`x`和`n`最多 10 个，最多可以有 100 个测试用例。 这意味着即使是显式构建序列的直接模拟也会快速运行。 然而，该问题也可以在根本不构建序列的情况下以数学方式解决，这简化了解决方案并降低了差一错误的风险。 

当出现微妙的边缘情况时`n`很奇怪。 该序列然后以`x`，留下一个非零和。 如果`n`是偶数，则该序列的个数相等`x`和`-x`，结果总和为零。 总是对对求和或忽略最后一个元素的粗心实现可能会产生不正确的结果。 

## 方法

 蛮力方法很简单：对于每个测试用例，显式构造序列并对所有元素求和。 这有效是因为`n`最多 10。在 Python 中，这将涉及迭代`n`次并交替添加`x`和`-x`到一个运行总数。 最坏情况下的操作总数为 100 个测试用例 × 每个序列 10 个元素 = 1000 次添加，可以忽略不计。 

最佳方法观察一种模式。 每一个连续的对`(x, -x)`总和为零。 因此，如果`n`是偶数，总和自动为零。 如果`n`是奇数，总和等于`x`因为所有对都取消并且额外的`x`最后剩下。 这种见解将问题简化为简单的奇偶校验检查`n`以及可能添加的`x`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n × t) | O(n) | 由于小的限制而被接受 |
 | 最佳 | O(t) | O(1) | O(1) | 公认、最简单、最安全|

 ## 算法演练

 1.读取测试用例数量`t`。 这决定了我们需要处理多少个序列。 
2. 对于每个测试用例，请阅读`x`和`n`。 
3. 检查是否`n`是均匀的。 如果是，则总和为零，因为所有对`(x, -x)`互相取消。 
4. 如果`n`是奇数，总和等于`x`因为所有对都取消并且额外的`x`最后贡献于总和。 
5. 打印每个测试用例的结果。 

为什么它有效：该算法依赖于每对连续元素的不变量`(x, -x)`总和为零。 通过以这种方式配对元素，问题就简化为检查是否有未配对的元素`x`仍然存在，这恰好发生在`n`很奇怪。 任何序列元素都不会被重复计算或忽略。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    x, n = map(int, input().split())
    if n % 2 == 0:
        print(0)
    else:
        print(x)
```第一行读取测试用例的数量。 对于每个测试用例，`x`和`n`已阅读。 支票`n % 2 == 0`确定序列长度是偶数还是奇数。 该条件直接实现算法演练中导出的逻辑。 因为我们利用了奇偶校验属性，所以序列元素上没有循环。 

## 工作示例

 **示例1：**输入`x = 1, n = 4`| 步骤| n % 2 | 总和 |
 | --- | --- | --- |
 | 检查奇偶校验| 4 % 2 = 0 | 0 |

 顺序`1, -1, 1, -1`总和为零。 我们的算法正确输出`0`。 

**示例2：**输入`x = 2, n = 5`| 步骤| n % 2 | 总和 |
 | --- | --- | --- |
 | 检查奇偶校验| 5 % 2 = 1 | 2 |

 顺序`2, -2, 2, -2, 2`有 4 个元素被取消，剩下 1 个元素`2`。 我们的算法输出`2`正如预期的那样。 

这些痕迹证实基于奇偶校验的方法可以正确处理偶数和奇数序列长度。

 ## 边缘情况

 对于最小序列`n = 1`， 输入`x = 1`产生序列`[1]`。 我们的算法发现`n % 2 == 1`和输出`1`，与总和相匹配。 对于最大序列`n = 10`， 输入`x = 10`产生`[10, -10, 10, -10, 10, -10, 10, -10, 10, -10]`。 我们的算法看到`n % 2 == 0`和输出`0`，这是正确的。 这表明该算法无需迭代序列即可处理两个边界。
