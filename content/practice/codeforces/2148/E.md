 ## 解决方案
 ## 问题理解

 我们得到一个正整数数组和一个参数$k$。 对于任何选定的细分市场$[l, r]$，我们想象将数组分成两部分：段内和段外。 

段内的每个元素都被强制放入一个独特的多重集，称为桶 1。段外的每个元素都可以任意分布在所有元素中。$k$多组，包括桶 1。 

当我们可以分配外部元素以便所有元素都可以时，该段被认为是有效的$k$多重集最终与多重集相同。 这意味着对于每个值$v$，每个桶必须包含完全相同的出现次数$v$。 

输出询问有多少段$[l, r]$使这种完美的平衡成为可能。 

关键的限制是我们可以自由分配外部元素，但内部元素固定在桶 1 中，因此它们会产生强制不平衡，必须使用外部元素进行补偿。 

输入大小可达$2 \cdot 10^5$测试中的总计，因此任何尝试所有子阵列并独立重新计算频率信息的解决方案都将是二次的，并且不会通过。 甚至$O(n \sqrt{n})$有风险。 我们应该期望每个测试用例都接近线性或线性对数。 

朴素推理的一个微妙的失败案例是假设“我们只需要每个值至少出现$k$整个数组中的次”。这还不够，因为分布约束是每个段的，并且与内部元素如何强制进入存储桶 1 相互作用。

 例如，如果$k=2$数组是$[1, 2, 1]$, 取段$[2,2]$隔离桶 1 内的单个 2。外部仅剩下一个 2，因此我们无法平等地平衡两个桶。 一个幼稚的全局计数论证会忽略这一点。 

另一个失败的情况是假设有效段的单调性。 即使$[l, r]$是有效的，将其扩展到$[l, r+1]$可能会破坏可行性，因为在铲斗 1 中添加受力元件会增加不平衡性，而这种不平衡性可能无法修复。 

## 方法

 蛮力方法尝试每个部分$[l, r]$。 对于每个段，我们计算每个值在其中出现的次数。 然后我们检查外部部分是否可以分成$k$相同的多重集。 

这需要验证每个值$v$，总计数$v$内部出现的负数可以整除$k$，因为外部元素必须均匀分布在$k$桶。 这个条件是必要的，但不是充分的； 我们还必须确保桶 1 的强制内部元素与最终的相等配置相匹配。 

如果我们尝试独立计算所有段的内部计数，则每次检查都会花费$O(n)$，导致$O(n^3)$如果天真地这样做，或者$O(n^2)$带前缀和。 甚至$O(n^2)$太慢了$2 \cdot 10^5$。 

关键的见解是扭转观点。 我们不考虑平衡所有存储桶，而是关注存储桶 1 的作用。 

让$cnt_v$是值出现的总次数$v$，并让$x_v$里面有多少个$[l,r]$。 在最终状态下，每个桶必须有相同数量的$v$， 说$t_v$。 那么总计就是$k \cdot t_v$， 所以$cnt_v$必须能整除$k$， 和$t_v = cnt_v / k$。 

现在桶 1 必须恰好包含$t_v$每个的副本$v$。 这意味着我们强制在该段内$x_v \le t_v$，并且外部必须提供剩余的$t_v - x_v$。 由于外部元素可以自由分配，唯一的限制是对于每个值，我们不能超过存储桶 1 中的目标分配。 

因此该段对于每个值都有效$v$,$$x_v \le \frac{cnt_v}{k}$$这将问题转化为经典的滑动窗口约束问题：找到频率不超过阈值的子数组。 

我们预先计算$t_v$。 然后我们维护一个两指针窗口并跟踪当前频率。 我们扩展右指针，每当任何频率超过其阈值时，我们就从左收缩，直到恢复所有约束。 对于每个右端点，有效左端点的数量恰好是当前窗口大小。 

这会为每个测试用例生成一个线性解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$或者更糟|$O(n)$| 太慢了 |
 | 最佳 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 计算数组中每个值的出现次数。 

这是必要的，因为每个存储桶的最终目标取决于全局频率，而不是本地分段。 
2. 计算每个值的目标容量：$t_v = cnt_v / k$。 

如果$cnt_v$不能被整除$k$，那么有效的子数组就不能包含任何违反此全局要求的出现模式。 然而，我们只使用$t_v$作为每个值的上限。 
3.用两个指针维护一个滑动窗口$l$和$r$，以及窗口内值的频率图。 

窗口代表一个候选子数组$[l, r]$。 
4. 扩展$r$逐步添加$a[r]$进入窗口频率。 

每次插入后，检查是否$freq[a[r]] > t_{a[r]}$。 如果是这样，则该窗口违反了可行性，因为存储桶 1 需要的值副本数量超出了允许的数量。 
5. 如果发生违规，请移走$l$直到所有频率都满足$freq[v] \le t_v$。 

这是可行的，因为缩小只会消除窗口的约束，因此可行性只会提高。 
6. 一旦窗口有效，所有以$r$并从任意位置开始$[l, r]$是有效的。 添加$r - l + 1$到答案。 

### 为什么它有效

 对于任何固定值$v$，最终配置强制存储桶 1 恰好包含$t_v$副本。 如果一个窗口包含超过$t_v$，那么该段至少需要放置$t_v + 1$的副本$v$进入桶 1，这是不可能的，因为只有$t_v$副本存在于目标平衡配置中。 

相反，如果窗口内的每个值都遵循其上限，我们总是可以将窗口外的剩余元素分配到桶中，以便每个桶与桶 1 完全匹配。 外部部分具有足够的灵活性，因为它不受约束并且仅需要匹配剩余的所需计数。 

因此滑动窗口准确地保持了可行性条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1

        cap = {}
        for x, c in freq.items():
            cap[x] = c // k

        cur = {}
        l = 0
        ans = 0

        for r in range(n):
            x = a[r]
            cur[x] = cur.get(x, 0) + 1

            while cur[x] > cap[x]:
                y = a[l]
                cur[y] -= 1
                l += 1

            ans += (r - l + 1)

        print(ans)

if __name__ == "__main__":
    solve()
```该实现依赖于当前窗口的频率字典和从全局计数派生的预先计算的上限字典。 关键的微妙之处在于，窗口始终从左侧保持最小，因此每次我们扩展右侧指针时，有效起始位置的数量恰好是当前窗口长度。 

一个常见的错误是忘记收缩必须持续到最后插入的元素再次有效为止。 另一个错误是使用总计数而不是整数除以$k$对于上限，这打破了可行性条件。

 ## 边缘情况

 当所有元素都相同时，上限变为$n/k$，滑动窗口不断增长，直到达到该限制。 任何超出该范围的尝试都会迫使左指针移动，从而产生连续的有效段块。 这证实了以下不变量：没有窗口会超过每个值的配额。 

什么时候$k = n$，每个上限根据频率变为 0 或 1，因此大多数窗口会立即崩溃。 该算法仍然可以正确运行，因为每个违规都通过收缩来解决，从而确保不会计算无效子数组。 

当值均匀分布时，例如重复对，窗口会平滑扩展，而无需频繁重置。 这种情况证实了该算法不会过度收缩并保留最大有效间隔以有效地计算所有子数组。
