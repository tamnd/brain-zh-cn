 ## 解决方案
 ## 问题理解

 每节车厢最初载有一定数量的乘客。 一名乘客开始乘坐车厢`i`可以向左或向右移动，但不能越过`D_i`门。 这意味着车厢内的每位乘客`i`必须在区间内的某个地方结束$$[i-D_i,\; i+D_i]$$将端点剪切到有效范围后`1..N`。 

只要每位乘客停留在出发车厢允许的间隔内，我们就可以自由地重新分配乘客。 

目标不是最小化总移动量。 相反，我们希望火车尽可能平衡。 所有动作完成后，让`Z`成为所有车厢中乘客人数最多的。 我们必须找到可实现的最小值`Z`。 

正是这些限制使问题变得有趣。 最多有`2 · 10^5`车厢和乘客数量可多达`10^9`。 任何显式移动乘客、构建每个乘客一个节点的流程图或尝试所有可能的最终分布的算法都是立即不可能的。 甚至一个`O(N^2)`算法需要大约`4 · 10^10`最坏情况下的操作。 

运动限制的结构是观察的关键。 车厢内每组乘客`i`只能在一个连续的区间内进行分配。 该区间结构比任意图简单得多。 

一些边缘情况很容易被忽略。 

考虑：```
1
10
0
```只有一辆马车，没有人可以移动。 答案是`10`。 任何假设重新分配总是可能的解决方案都会在这里失败。 

考虑：```
2
5 0
0 0
```任何人都不能离开他们的出发马车。 答案是`5`， 不是`3`。 当运动限制阻碍平衡时，总平均值并不重要。 

考虑：```
3
3 3 3
2 2 2
```每个乘客都可以到达每节车厢。 有`9`乘客和`3`车，所以答案是`3`。 仅考虑局部约束的解决方案可能会错误地返回更大的值。 

主要困难是确定建议值是否`Z`是可行的。 

## 方法

 一个暴力的观点是猜测每节车厢的最终乘客人数，并检查是否可以将所有乘客运送到那里。 即使我们以某种方式限制每节车厢最多`Z`乘客，有指数级多种可能的分布。 这是没有希望的。 

一个更复杂的暴力思想是将问题建模为流网络。 每个出发车厢贡献`A_i`流量单位。 每个目的地车厢都有容量`Z`。 连接源间隔`i`到每一个可到达目的地的车厢。 

这是正确的，但该图最多包含$$\sum (2D_i+1)$$边缘，可以是`Θ(N^2)`在最坏的情况下。 和`N = 2 · 10^5`，那太大了。 

转折点来自于注意到每个乘客组对应于线路上的单个区间。 区间分配问题通常允许贪婪的扫线解决方案。 

假设我们修复一些候选值`Z`。 现在每节车厢都有容量`Z`，意味着它最多可以接受`Z`旅客最终安排。 

用于运输`i`，我们有一个需求`A_i`必须安排在间隔内某处的乘客`[L_i, R_i]`。 

这变成：

 “是否可以将所有间隔需求分配到位置`1..N`，其中每个位置都有能力`Z`？”

 可行性问题是单调的。 如果容量`Z`可以，那么任何更大的容量也可以。 这立即表明对答案进行二分搜索。 

剩下的任务是有效的可行性测试。 

从左向右扫过目的地车厢。 当我们到达位置时`x`，左端点为的每个区间`x`变得活跃。 该职位的容量为`Z`。 

为了最佳地利用该容量，我们应该始终首先为最小右端点的活动间隔提供服务。 间隔越早到期越紧急。 这与最早截止日期优先调度中出现的交换参数相同。 

按右端点排序的最小堆正是我们所需要的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 流程/显式分配 | 至少 O(N²) | O(N²) | 太慢了 |
 | 二分查找+贪心区间扫描| O(N log N log S) | O(N log N log S) | O(N) | 已接受 |

 这里`S = sum(A_i)`。 

## 算法演练

 ### 修复的可行性检查`Z`对于每节车厢`i`， 定义：$$L_i = \max(1, i-D_i)$$

$$R_i = \min(N, i+D_i)$$运输`i`贡献了一个需求`A_i`必须被分配到内部某处的乘客`[L_i, R_i]`。 

我们从左到右扫描目标位置。 

1. 创建从每个位置开始的间隔列表。 
2. 维护按其右端点排序的活动间隔的最小堆。 
3.到达位置时`x`，插入所有区间`L_i = x`到堆中。 
4. 在使用容量之前，检查某个活动间隔是否已经存在`R_i < x`。 如果这样的间隔仍然存在，则说明其截止日期已过，并且无法进行分配。 
5. 职位`x`有可用容量`Z`。 
6. 重复取最小右端点的活动区间。 
7. 为该间隔分配尽可能多的容量。 
8. 如果完全满足该间隔，则将其永久删除。 
9. 舱位剩余运力耗尽后，该区间是否仍需要乘客`x`，将其放回到堆中并继续。 
10. 定位后`x`被处理，如果任何活动间隔有`R_i = x`，它一定已经完全满足了。 否则可行性失败。 
11. 处理完所有位置后，只有当没有剩余未完成的区间时，可行性才成功。 

### 二分查找

 1. 设置`low = 0`。 
2. 设置`high = sum(A)`。 
3.二分查找最小`Z`可行性测试成功。 
4. 输出该值。 

### 为什么它有效

 在任何目标位置，假设我们将容量分配给具有较晚右端点的间隔，而另一个活动间隔则较早到期。 

如果较早的间隔后来变得无法满足，我们可以交换部分分配并将该容量分配给较早的间隔。 较晚的时间间隔在未来头寸中仍然至少有同样多的剩余空间，因为它的截止日期并不早。 

反复应用此交换参数表明，以右端点递增顺序提供活动间隔始终至少与任何其他选择一样好。 

扫描保证每个间隔仅在其允许的范围内接收容量。 每当一个间隔到达其右端点时，算法就会检查其全部需求是否已被分配。 因此，每个接受的作业都满足所有约束。 

因为可行性是单调的`Z`，二分查找找到最小可行值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from heapq import heappush, heappop

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    d = list(map(int, input().split()))

    starts = [[] for _ in range(n + 2)]

    for i in range(n):
        l = max(1, i + 1 - d[i])
        r = min(n, i + 1 + d[i])
        starts[l].append((r, a[i]))

    total = sum(a)

    def feasible(z):
        heap = []

        for pos in range(1, n + 1):
            for r, amt in starts[pos]:
                heappush(heap, (r, amt))

            while heap and heap[0][0] < pos:
                return False

            cap = z

            while cap > 0 and heap:
                r, need = heappop(heap)

                take = min(cap, need)
                cap -= take
                need -= take

                if need:
                    heappush(heap, (r, need))
                    break

            while heap and heap[0][0] == pos:
                return False

        return not heap

    lo, hi = 0, total

    while lo < hi:
        mid = (lo + hi) // 2
        if feasible(mid):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

solve()
```预处理将每个起始车厢转换为一个区间`[L_i, R_i]`连同需求`A_i`。 

这`starts`数组让我们可以在间隔变为活动状态时将其插入堆中。 这避免了在扫描期间重复扫描所有间隔。 

堆存储对`(right_endpoint, remaining_demand)`。 总是首先处理最小的右端点。 

一个微妙的点是`break`重新插入部分满足的区间后。 一旦当前位置用完容量，则任何其他间隔都无法从该位置接收任何内容。 重新插入并继续只会浪费时间。 

另一个微妙的点是截止日期检查。 使用位置前`pos`, 任意区间`r < pos`已经过期并且一定会导致失败。 使用位置后`pos`，任何剩余间隔`r == pos`也会导致失败，因为这是其获得容量的最后机会。 

旅客数量可达到`10^9`，因此所有算术都必须使用能够容纳大值的整数来完成。 Python 自然地处理这个问题。

 ## 边缘情况

 考虑：```
1
10
0
```间隔为`[1,1]`。 在可行性检查期间，所有十名乘客必须留在唯一的车厢内。 任何`Z < 10`职位后留下未满足的需求`1`，所以检查失败。`Z = 10`成功了。 

考虑：```
2
5 0
0 0
```间隔是`[1,1]`和`[2,2]`。 测试时`Z = 4`， 位置`1`有能力`4`但要求`5`立即过期。 加工后位置`1`，具有右端点的未完成区间`1`仍然存在，因此算法正确地拒绝了它。`Z = 5`是第一个可行值。 

考虑：```
3
3 3 3
2 2 2
```所有间隔均为`[1,3]`。 堆始终包含长期间隔，因此不会发生截止日期故障。 可行性仅取决于总容量。 扫掠消耗正好`3Z`容量，必须至少为`9`。 最小可行值为`3`。 

这些案例说明了问题的两个极端。 有些实例完全由本地截止日期控制，而其他实例则表现得像纯粹的负载平衡。 扫描线可行性测试以相同的不变量处理两者：每个间隔必须在通过其右端点之前接收其所有需求。
