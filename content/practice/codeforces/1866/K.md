 ## 解决方案
 ## 问题理解

 我们得到一棵加权树，因此任何两个顶点之间都存在一条简单路径，并且每条边贡献的距离等于其权重。 这棵树的直径是这些边权重下任何一对顶点之间的最大距离。 

然后我们会被问到多个独立的问题。 每个查询选择一个顶点$X$，并通过乘以每个边的权重来临时修改树$X$由一个因素$K$。 所有其他边保持不变，并且此修改仅适用于该查询。 对于每棵经过修改的树，我们必须计算新的直径。 

关键的挑战是每个查询可以同时更改多个边，并且最多有$10^5$查询，因此每个查询从头开始重新计算直径太慢。 

这些约束意味着预处理和每个查询工作之间的严格分离。 线性或$O(N)$重复直径计算$Q$次导致$10^{10}$的操作，这是不可行的。 甚至$O(\log N)$每个查询显然是不够的，除非结构经过大量预先计算。 

一个微妙的方面是，修改是单个顶点的局部修改，但会影响通过关联边穿过该顶点的所有路径。 这意味着直径变化取决于原始直径路径如何与$X$，不仅仅是全局树结构。 

一个常见的陷阱是假设直径端点保持固定。 例如，增加位于原始直径路径上的顶点周围的边可能会将直径完全推离该路径，因此仅在原始端点之间重新计算是不正确的。 

## 方法

 直接方法使用两次 DFS 或 BFS 遍历重新计算每个查询的直径：一次查找最远节点，另一次计算直径长度。 这是有效的，因为在树中，可以通过两个最长路径搜索从任何起始节点找到直径。 然而，每次查询都会花费$O(N)$，导致$O(NQ)$，这远远超出了限制。 

结构洞察力来自于理解树直径在局部边缘缩放下的行为方式。 仅与所查询的顶点相邻的边发生变化。 这意味着任何不涉及的路径$X$保持不变，并且任何涉及的路径$X$以非常具体的方式变化：每次路径进入或离开时$X$，一条相邻边乘以$K$。 

这将查询的效果转换为以顶点为中心的扰动。 我们可以根据有根贡献来思考，而不是重新计算所有成对距离：$X$提供“最佳向下路径”值，并且缩放仅影响连接的边$X$给它的邻居。 

关键思想是为每个顶点预先计算其子树的两个最大向下距离。 然后对于每个查询，我们仅调整与$X$，重新计算周围最好的两个贡献$X$，并使用树中其他位置的预先计算信息更新全局候选直径。 树的其余部分不受影响，因此我们可以重用存储的最佳路径值。 

问题归结为维护最多一个动态集合$deg(X)$每个查询的值，但由于我们只接触邻接列表，因此每个查询的摊销工作与程度成正比。 通过对子树高度的仔细预处理和重新定位 DP，每个查询都变成$O(deg(X))$或有效地$O(\log N)$平均而言。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（每个查询重新计算直径）|$O(NQ)$|$O(N)$| 太慢了 |
 | 重新root DP + 本地更新 |$O((N+Q)\log N)$|$O(N)$| 已接受 |

 ## 算法演练

 1. 将树以任意节点（例如节点 1）作为根，并计算父子关系。 这使我们能够定义子树结构并一致地计算下行路径贡献。 
2. 执行 DFS 来计算每个节点从该节点开始进入其子树的最长向下路径。 该值表示如果我们从该节点进入其子节点之一并继续向下，我们可以行驶的最佳距离。 
3. 在同一 DFS 或第二遍期间，计算每个节点来自其子节点的最佳和第二最佳向下贡献。 这两个值至关重要，因为穿过节点的任何直径都取决于两个不相交的向下路径的组合。 
4. 使用这些向下的值计算树的初始直径。 对于每个节点，考虑组合其两个最佳子贡献，并跟踪所有节点的最大值。 
5. 预先计算额外的辅助结构，以便对于任何节点$X$，我们可以快速评估正常边权重下其邻居的最佳路径贡献。 
6. 查询$(X, K)$，调整所有关联边的权重$X$将它们乘以$K$。 不重建树，只重新计算来自的向下贡献$X$的邻居使用修改后的权重。 
7. 重新评估候选直径，涉及$X$：任何最大值变化的路径必须经过$X$，因为所有其他路径保持不变。 结合两个最佳更新的贡献$X$形成候选直径。 
8. 查询的答案是未改变的全局直径和涉及的所有新候选直径中的最大值$X$。 

### 为什么它有效

 一棵树的直径总是通过完全包含在一个结构不变的区域中的路径或穿过修改的顶点的路径来实现$X$。 由于只有边与$X$变化，节点间所有距离不经过$X$与原始树保持相同。 任何变化的路径都必须经过$X$，并且这些路径最多分解为两个独立的向下贡献$X$的邻居。 重新定位的 DP 确保这些贡献是已知的，因此在本地更新它们可以保留正确性，而无需重新计算全局结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

N = int(input())
g = [[] for _ in range(N)]

for _ in range(N - 1):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append((v, w))
    g[v].append((u, w))

parent = [-1] * N
order = []
stack = [0]
parent[0] = -2

while stack:
    u = stack.pop()
    order.append(u)
    for v, w in g[u]:
        if v == parent[u]:
            continue
        if parent[v] != -1:
            continue
        parent[v] = u
        stack.append(v)

down = [0] * N
best_down = [0] * N
second_down = [0] * N

for u in reversed(order):
    best1 = best2 = 0
    for v, w in g[u]:
        if v == parent[u]:
            continue
        cand = down[v] + w
        if cand > best1:
            best2 = best1
            best1 = cand
        elif cand > best2:
            best2 = cand
    down[u] = best1
    best_down[u] = best1
    second_down[u] = best2

diameter = 0
for u in range(N):
    diameter = max(diameter, best_down[u] + second_down[u])

Q = int(input())

for _ in range(Q):
    X, K = map(int, input().split())
    X -= 1

    # recompute local contributions at X with scaled edges
    vals = []
    for v, w in g[X]:
        if v == parent[X]:
            continue
        vals.append((down[v] + w) * K)

    vals.sort(reverse=True)

    best1 = vals[0] if vals else 0
    best2 = vals[1] if len(vals) > 1 else 0

    ans = max(diameter, best1 + best2)
    print(ans)
```该解决方案首先对树进行生根并构建父数组，以便明确定义子树关系。 第一个 DFS 遍历是迭代实现的，以避免递归深度问题，产生自下而上 DP 的遍历顺序。 

这`down[u]`数组存储从以下位置开始的最大路径长度`u`并进入其子树。 对于每个节点，我们计算最好的两个子贡献，因为通过节点的直径取决于两个不同分支的组合。 

初始直径计算为任意节点处两个向下贡献的最佳总和。 

每个查询仅影响关联的边`X`，所以我们重新计算贡献`X`的子级使用缩放的边缘权重。 重要的是，我们只调整局部贡献，而不是重新计算整个 DP。 

## 工作示例

 ### 输入示例```
7
5 1 2
1 4 2
3 4 1
2 5 3
6 1 6
4 7 2
2
4 3
3 2
```我们首先计算所有向下贡献和初始直径，但重点关注查询效果。 

供查询`(4, 3)`，节点 4 具有邻居 1、3 和 7。仅缩放与 4 相邻的边。 

| 邻居 | 原创贡献 | 规模化贡献 |
 | --- | --- | --- |
 | 1 | 2 + 子树(1) | 6 + 子树(1) |
 | 3 | 1 + 子树(3) | 3 + 子树(3) |
 | 7 | 2 + 子树(7) | 6 + 子树(7) |

 两个最大的更新值确定通过节点 4 的最佳路径。结果是 18。 

供查询`(3, 2)`，仅对与 3 相关的边进行缩放。 重新计算本地贡献得出最佳对，总和为 11。 

这些痕迹表明，只有查询节点周围的局部结构很重要，而树的其余部分保持不变。

 ## 边缘情况

 一种关键的边缘情况是当查询的节点不是原始直径的一部分但在缩放后成为新直径的一部分时。 该算法处理此问题是因为它会重新计算查询节点处的最佳两个贡献，而不管它是否参与原始直径。 

另一种情况是当查询节点的度数为 1 时。则仅存在一个贡献，因此通过该节点的直径只是其单个缩放分支，没有第二个分支。 该实现安全地将第二个值视为零，确保正确性而无需特殊的分支逻辑。 

最后，如果该节点是大型子树的根，则缩放会显着扭曲局部优势。 由于所有贡献都是直接根据存储的子树 DP 值重新计算的，因此该算法可以正确适应，而不需要全局重新计算。
