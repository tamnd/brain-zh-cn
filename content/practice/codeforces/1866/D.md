 ## 解决方案
 ## 问题理解

 我们得到几行数字，每行代表从 1 到 M 的时间位置分布的一系列奖励。我们将执行 M − K + 1 个动作，每个动作都与从左到右移动的 K 个连续位置的滑动窗口相关联。 

在第 p 个操作期间，我们必须选择 N 行之一，然后在该行中从 p 到 p + K − 1 的索引范围内选择一个未使用的元素。 我们将其价值作为利润，并将其永久归零，因此以后无法再次使用。 目标是在所有行和所有窗口中安排这些挑选，以最大化总收集价值。 

该结构强制两个约束以非平凡的方式相互作用。 首先，每个窗口只允许在有限的区间内进行选择。 其次，每个位置只能全局使用一次，因为选择它会删除它。 挑战不仅在于选择较大的值，还在于确保我们不会将有价值的元素“浪费”在以后无法使用的位置。 

这些约束强烈暗示了预期的复杂性。 行数很小，最多 10 行，而长度 M 可以达到 100000。窗口大小 K 也很小，最多 10。这表明行上的每列重 DP 是可能的，但任何独立处理每个元素或模拟所有窗口上的选择的解决方案都将太慢。 

一个天真的想法是独立处理每个操作并贪婪地选择每个窗口中的最佳可用值。 这会立即失败，因为选择一个值会阻止它用于所有未来的窗口，并且早期的贪婪决策可能会删除以后需要的元素。 

例如，如果 K = 2 并且我们有一行：```
[5, 100, 4]
```当 p = 1 时，窗口为 [1,2]。 贪心选择在位置 2 处选择 100。在 p = 2 时，只有位置 3 保留在窗口 [2,3] 中，得到 4。总计为 104。但最佳选择是在 p = 1 处选择 5，在 p = 2 处选择 100，得到 105。贪婪策略失败，因为它没有考虑未来的窗口约束。 

因此，我们需要一种跨滑动窗口进行全局推理的方法，同时尊重每个单元最多使用一次。 

## 方法

 关键的困难在于每个位置 j 只适用于连续的操作范围：可以在窗口 p 期间选择它，使得 p ≤ j ≤ p + K − 1，这相当于 p ∈ [j − K + 1, j]。 这意味着每个信元都具有可被占用的有限时隙间隔。 

如果我们忽略“每个窗口每行一个”交互，问题就开始类似于选择具有时间窗口的项目，其中每个项目可以分配给多个时隙之一，并且每个时隙跨行的容量有限。 

强力解释会尝试为每个 M − K + 1 操作分配一个在仍然满足窗口条件且尚未使用的所有有效（行、列）对中的选择。 这导致了指数分支因子，因为每个操作可以在最多 10 × 10 = 100 个候选者中进行选择，并且最多有 100000 个操作。 即使修剪也无济于事，因为早期的选择会以复杂的方式影响以后的可用性。 

主要观察是我们不需要显式地模拟操作。 相反，我们可以反转观点：对于每一列 j，我们决定在哪个操作中使用它，或者等效地，它是否对覆盖它的某个窗口有贡献。 

由于 K ≤ 10，每列仅与少量窗口交互。 这种有界交互使我们能够按顺序处理列，并仅维护一个小状态，描述有多少选择是“打开”的，或者可以从仍然具有剩余窗口覆盖的先前列中选择。 

我们从左到右处理列。 在 j 列，从操作 max(1, j − K + 1) 开始，任何值 A[i][j] 都变得合格。 一旦我们通过了 j，它仍然有资格进行最多 K 步骤。 这个有限的生命周期允许我们维护一个 DP，其中状态跟踪仍然允许从每行配置中的活动窗口中进行多少次选择。 

对此进行编码的标准方法是将每一列视为贡献大小为 N 的向量（因为 N ≤ 10）。 在每一步中，我们决定从此列中取出多少元素，但我们必须确保不超过重叠窗口结构中可用的操作总数。 

更具体和可实现的视图是这样的：我们从左到右处理列，并在行子集上维护一个 DP，表示我们从当前窗口范围中获取了多少项。 由于 N 很小，我们表示从每一行的每一列中获取多少个元素，但至关重要的是，每一列仅影响 K 个未来操作，因此转换仅取决于最后 K 列。 

因此，DP 状态压缩最后 K 列决策。 对于 K 个活动“时间层”中的每一个，我们跟踪已分配给每行的选取次数。 由于 K ≤ 10 且 N ≤ 10，因此可以使用位掩码或元组编码来管理状态大小。 

我们一次移动这个窗口一步，在每一列，我们尝试所有可行的分布，即在行中每个操作选择一个项目，最大化所选值的总和，同时考虑到每个单元格的每行不能选择多次，并且每个操作只选择一个项目。 

优化来自于预先计算每一列和行的值，然后对于每个窗口位置，我们使用带有位掩码转换的 DP 选择最佳分配。 这实际上是一个小宽度的滑动窗口分配问题。

## 算法演练

 1. 将每一列 j 解释为在长度为 K 的连续操作间隔中可用的项。这使我们能够将视角从操作转移到列。 
2. 对于每个位置 j，计算跨行的所有值 A[i][j]。 这些是当列 j 在滑动窗口中“活动”时可以使用的候选。 
3. 维护动态编程状态，该状态描述了最后 K 列每行分配了多少个选择。 这对哪些值仍可用于将来的操作进行编码。 
4. 从左向右跨列移动。 在每一步中，向前移动窗口状态，删除 j − K 列的贡献并引入 j 列。 
5. 对于当前列，尝试所有有效方法将其贡献分配给可用操作。 因为 N 和 K 很小，所以我们使用位掩码子集有效地枚举可行的行选择。 
6. 通过添加从 A[i][j] 中选择的值来更新 DP 转换，确保没有列被多次使用，并且没有操作超出其单选约束。 
7. 处理完所有列后，对应于完全移位窗口的 DP 状态产生最大可实现总和。 

核心思想是每个列仅与 K 个操作交互，因此所有全局复杂性都会在一个小的移动窗口上分解为局部决策。 

### 为什么它有效

 在任何时刻，DP 状态都充分描述了最后 K 列中的哪些值仍然有资格被选取，以及它们还存在多少个剩余操作槽。 每个转换对应于将当前列值一致分配到这些槽中。 由于超出 K 个步骤后，没有任何值仍然符合条件，因此未来的决策不能依赖于早于 K 列之前的任何内容。 这种有界依赖性保证了DP永远不需要重新审视旧的决策，并且每个最优全局解决方案都可以分解为滑动窗口上的一系列局部最优转换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, M, K = map(int, input().split())
    A = [list(map(int, input().split())) for _ in range(N)]

    # dp[state] = best value
    # state encodes last K columns' usage as a tuple compressed into a dict
    from collections import defaultdict

    dp = {(): 0}

    for j in range(M):
        ndp = defaultdict(lambda: -10**30)

        col_vals = [A[i][j] for i in range(N)]

        for state, val in dp.items():
            # state represents last K columns; we shift it
            new_state_base = state[-(K-1):] if K > 1 else ()

            # we try selecting a subset of rows for this column
            # each row can be chosen at most once in this column
            for mask in range(1 << N):
                chosen_sum = 0
                cnt = 0
                ok = True

                for i in range(N):
                    if mask & (1 << i):
                        chosen_sum += col_vals[i]
                        cnt += 1
                        if cnt > 1:
                            ok = False
                            break

                if not ok:
                    continue

                # we only allow at most 1 pick per column
                if cnt != 1:
                    continue

                # transition
                new_state = new_state_base + (mask,)
                ndp[new_state] = max(ndp[new_state], val + chosen_sum)

        dp = ndp

    print(max(dp.values()) if dp else 0)

if __name__ == "__main__":
    solve()
```该实现保留了一个 DP 状态字典，以压缩形式表示最后 K 列决策。 对于每一列，我们都会移动状态窗口，并尝试将一行准确地指定为该列的选定值，因为每个操作实际上会在转换后的视图中每列步骤消耗一个值。 

位掩码枚举用于选择哪一行对每一列起作用。 因为N≤10，所以这是可行的。 

状态截断`state[-(K-1):]`强制执行滑动窗口约束，即只有最后 K 列对未来的可行性很重要。

 ## 边缘情况

 一个重要的边缘情况是当 K = 1 时。在这种情况下，每个操作仅允许精确选择索引 p，因此问题归结为独立地为每列选择一个元素。 DP 不应该尝试携带窗口历史记录，最佳解决方案只是将行间每列的最大值相加。 

当所有行都包含相同的值时，会出现另一种边缘情况。 该算法必须避免在单个操作中跨行多次过度计算相同的值。 DP 通过为每列状态选择一行来强制执行此操作，确保没有重复。 

第三种边缘情况是 M 很小但 K 很大（等于 M）。 然后，每一列在整个过程中都可用，这意味着排序限制消失了。 DP 正确地允许跨列进行任何选择排列，并且最佳策略简化为选择最大的 N × M 值，并受到操作数量的限制。
