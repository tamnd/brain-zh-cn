 ## 解决方案
 ## 问题理解

 我们在数轴上得到了两个隐藏配置。 有房子的位置$h_1, \dots, h_n$，还有两个特殊点$p_1$和$p_2$。 我们没有直接得到坐标。 相反，我们得到了两个多组距离：对于每栋房子，它到$p_1$并到$p_2$。 这些距离记录在数组中$d_1$和$d_2$，但是索引和房屋之间的对应关系在每个数组中丢失，这意味着每个数组只是一个多重集。 

任务是判断是否存在所有的位置$h_i$,$p_1$， 和$p_2$在一条线上，使得这两个距离多重集与绝对差一致。 如果存在这样的配置，我们必须构建一个。 

主要困难是我们正在从无序距离多重集重建几何。 每户贡献一对$(|h_i - p_1|, |h_i - p_2|)$，但这些对没有给出，只有它们的投影。 

约束足够小$n$每次测试最多 1000 个，总共 2000 个允许大致$O(n^2 \log n)$或者$O(n^2)$每个测试用例的解决方案。 任何立方体$n$是有风险的，但如果恒定因素很小，则可能几乎不会通过。 这表明我们应该尝试将问题减少到选择少量候选配置并验证它们。 

一个关键的微妙之处在于许多不同的几何配置会产生相同的距离多重集。 例如，交换$p_1$和$p_2$、平移所有点或反映直线均保持有效性。 另一个微妙的问题是，多个房屋可能会彼此重合或同时出现。$p_1$或者$p_2$，因此零距离必须自然处理，而不是作为特殊情况处理。 

一种常见的失败模式是尝试贪婪地匹配已排序的数组$d_1$和$d_2$索引方面。 这是不正确的，因为距离之间的配对没有被保留。 另一种不正确的方法是假设单调性，因为不同中心的距离不对齐。 

## 方法

 直接的暴力观点将尝试重建所有$n$对$(|h_i - p_1|, |h_i - p_2|)$通过匹配元素$d_1$和$d_2$。 这成为两个多重集之间的完美匹配问题，但并非每个匹配都对应于一条线上可实现的几何图形。 即使我们假设配对，我们仍然必须恢复满足绝对值约束的实际坐标，这引入了连续的自由度。 尝试所有配对都是阶乘$n$，这是不可能的。 

关键的观察是，一旦我们固定了位置，整个配置就由平移和反射决定了。$p_1$和$p_2$。 如果我们假设$p_1 = 0$和$p_2 = x$，那么每个房子的位置$h$必须满足它的两个距离恰好是$(|h|, |h-x|)$。 这将问题简化为检查对的多重集是否可以嵌入到某些行上$x$。 

核心结构见解是候选集合$x$值很小。 如果我们选择一栋房子，并假设它对应于$d_1$和一段距离$d_2$，我们可以得出潜在的位置$p_1$和$p_2$。 每对距离仅给出恒定数量的几何可能性，因为直线上的点是通过其到两个固定点的距离来确定反射的。 这会将搜索空间折叠为$O(n)$或者$O(n \log n)$候选结构。 

一次$p_1$和$p_2$是固定的，每个房屋位置都被迫为两个值之一：$p_1 \pm d_{1,i}$，并且我们必须选择方向，使其也匹配$d_2$。 这成为一致性检查，我们验证是否可以分配每个距离$d_1$到一个标志并将其与$d_2$引起的值$p_2$。 排序和多集验证就足够了。

 | --- | --- | --- | --- |
 | 距离的强力配对 |$O(n!)$|$O(n)$| 太慢了|
 | 从配对中修复候选人并验证 |$O(n^2 \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将构建候选人$p_1$和$p_2$并验证它们。 

1. 选择一个元素$a$从$d_1$和一个元素$b$从$d_2$。 将它们视为距某个房屋的距离$h$到$p_1$和$p_2$。 从一条直线上的几何图形，如果一个点$h$有距离$a$和$b$到两点$p_1$和$p_2$，那么之间的距离$p_1$和$p_2$必须是$a+b$或者$|a-b|$。 这最多给出两个候选值$x = |p_1 - p_2|$。 
2. 对于每位候选人$x$，尝试重建完整的配置。 使固定$p_1 = 0$,$p_2 = x$。 现在每个房子都必须满足它到 0 的距离是某个值$d_1$排列后，还有它到$x$必须匹配$d_2$。 
3. 建造房屋位置时，要保持距离$d$从$d_1$。 房子的位置是$+d$或者$-d$。 对于每个选择，计算其隐含距离$x$并检查它是否存在于$d_2$。 我们使用多重集进行贪婪匹配。 
4. 如果所有距离都能一致匹配，则输出构造的坐标。 

这样做的原因是一旦$p_1$和$p_2$是固定的，每个房子的位置都被限制为两点选择。 多重集匹配确保了全局一致性，因为每个选择都必须恰好消耗其中的一个元素$d_2$，任何冲突都表明错误的符号分配或错误的候选者$x$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import Counter

def try_build(d1, d2, x):
    c2 = Counter(d2)
    h = []

    for d in d1:
        candidates = [d, -d]
        chosen = None

        for v in candidates:
            dist2 = abs(v - x)
            if c2[dist2] > 0:
                chosen = v
                c2[dist2] -= 1
                break

        if chosen is None:
            return None
        h.append(chosen)

    return h

def solve_case(n, d1, d2):
    c1 = Counter(d1)
    c2 = Counter(d2)

    candidates = set()

    d1_list = list(c1.elements())
    d2_list = list(c2.elements())

    # generate possible x from one pair
    for i in range(n):
        for j in range(n):
            a = d1_list[i]
            b = d2_list[j]
            candidates.add(a + b)
            candidates.add(abs(a - b))

    for x in candidates:
        res = try_build(d1_list, d2_list, x)
        if res is None:
            continue

        p1 = 0
        p2 = x

        # shift to non-negative if needed
        minv = min(min(res), 0, x)
        shift = -minv
        res = [v + shift for v in res]
        p1 += shift
        p2 += shift

        return True, res, (p1, p2)

    return False, None, None

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        d1 = list(map(int, input().split()))
        d2 = list(map(int, input().split()))

        ok, h, p = solve_case(n, d1, d2)
        if not ok:
            print("NO")
        else:
            print("YES")
            print(*h)
            print(p[0], p[1])

if __name__ == "__main__":
    main()
```该实现的重点是测试候选者之间的距离$p_1$和$p_2$。 对于每位候选人$x$，我们尝试对每个进行贪心分配$d_1$值到有符号的位置，并立即检查与$d_2$使用多集计数器。 移位步骤确保所有坐标均为非负值，而不影响距离。 

一个微妙的点是，每个房子的贪婪选择是安全的，因为任何有效的全局解决方案都会导致一致的配对，并且无法找到特定的匹配$d_1$两个符号选项下的值都证明这是不可能的$x$。

 ## 边缘情况

 关键的边缘情况是两个数组都包含许多零。 这对应于正好位于$p_1$或者$p_2$。 该算法自然地处理了这个问题，因为零距离迫使房屋位置等于相应的枢轴，从而不会在分配中留下任何歧义。 

另一个边缘情况是当$p_1 = p_2$。 在这种情况下，两个数组必须是相同的多重集。 候选一代包括$x = 0$，并且重建退化为检查单个中心是否同时解释两个数组，贪婪匹配通过强制相同的距离来正确验证这一点。 

第三种边缘情况是当同一符号存在多个有效符号分配时$x$。 该算法仍然成功，因为它只需要一个一致的分​​配。 如果早期分配错误，稍后会由于多重集中不匹配的元素而失败，并且算法会重试其他候选者。
