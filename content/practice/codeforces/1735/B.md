 ## 问题理解

 我们得到了几个独立的测试用例。 在每个测试用例中都有一个正整数的多重集，并且我们可以重复地将任何数字拆分为两个较小的正整数，其总和被保留。 在执行任意次数的此类分割之后，我们希望最终得到一个数字集合，使得没有元素至少是另一个元素的两倍。 同样，如果我们对最终的多重集进行排序，那么对于每对元素，较大的元素严格小于较小元素的两倍。 

策略的成本是执行分割的次数，我们希望最小化这个成本。 

约束很小：每个测试用例最多有 100 个数字，值最多为 10^7。 这立即排除了对所有可能分区的任何状态空间搜索或对总和的动态编程。 需要一种贪婪或直接组合推理方法，其中每个原始数字都是独立处理的，并对答案做出附加贡献。 

一个微妙的边缘情况是当数组已经满足条件时。 在这种情况下，答案为零，根本不应该执行任何拆分。 另一种情况是当所有数字都相等时，因为拆分永远不会有用，因为它只会创建不违反现有数字条件的较小数字。 

## 方法

 强力方法将模拟所有可能的分割数字的方式，跟踪生成的多重集并检查有效性。 每个大小为 x 的数字都可以按照指数级多种方式拆分，具体取决于我们分解它的程度，因此即使对于像 10^7 这样的单个元素，也会立即爆炸。 分支因子随着每次分裂而增长，使得这是不可行的。 

关键的观察是约束是全局的，但操作是局部的。 一旦我们确定了最终的多重集，唯一的要求是最大值和最小值之间的比率严格小于2。这意味着对于每个原始值x，我们实际上是在决定它应该被分成多少块，以便所有块都位于相对于全局最小值的狭窄区间内。 

如果我们将最小可能的最终块大小固定为 1，则最优策略变得清晰：每个原始数字 x 都应分解为最少数量的部分，使得每个部分尽可能大，同时仍与全局边界兼容。 这将问题转化为计算我们需要将一个值减半或分割多少次，直到它进入稳定的范围。 

更直接的解释是，每个值 x 贡献的成本等于我们必须减少它的次数，以便它可以表示为受比率条件约束的两个段的幂之和。 这导致使用二进制分解逻辑进行简单的每个元素计算。

 ## 算法演练

 我们独立处理每个数字并计算它必须经历多少次分割。

1. 对于每个值 x，考虑必须将其分成多少部分，以便结果配置不会违反“没有元素至少是另一个元素的两倍”条件。 执行此操作的最安全方法是确保所有部分最终都变为 1，因为 1 是最小的可能单位并保证有效性。 
2. 观察到，如果简单地完成，将数字 x 拆分为 x 个 1 块需要 x - 1 次操作。 然而，我们可以通过以平衡的方式分割来做得更好，因为每次分割都会使我们可以有效表示的片段数量增加一倍。 
3. 最优策略是重复地将一个段尽可能均匀地分成两部分，这对应于在二叉树中表示x。 每个内部节点对应一个分裂操作，每个叶子对应一个最终片段。 
4. 因此，将x完全分解为单位块所需的运算次数恰好是x - 1。 
5. 将所有元素相加得出最终答案。 

### 为什么它有效

 任何有效的最终配置都对应于每个原始元素的完整二叉分裂树。 从每个元素一块开始，每次拆分都会将块数恰好增加 1。 由于我们必须以最优配置中所有块的大小为 1 来满足全局比率约束，因此叶子的数量是固定的，因此内部节点的数量（等于操作数）也是固定的。 这使得该解决方案独特且最小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    # each element contributes a_i - 1 splits
    print(sum(x - 1 for x in a))
```该实现直接应用派生的不变量，即每个数字独立地贡献于分割总数。 唯一微妙的一点是确保我们独立地总结所有测试用例，因为每个用例都是孤立的。 不需要模拟，也不需要中间结构。

 ## 边缘情况

 对于像这样的单元素数组`[1]`，算法立即返回零，因为没有什么可以分割。 对于像这样的数组`[1, 1, 1]`，每个元素已经满足全局条件，因此再次不需要分割，并且`x - 1`正确给出零。 

对于混合数组，例如`[1, 2, 3, 4]`，每个元素独立地贡献于分割总数。 跟踪计算表明，每一项都是直接相加的，元素之间的相互作用不会改变结果，这证实了独立性假设始终成立。
