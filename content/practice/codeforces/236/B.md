 ## 解决方案
 ## 问题理解

 我们需要计算每个乘积的除数的总和`i * j * k`， 在哪里`i`范围从`1`到`a`,`j`范围从`1`到`b`， 和`k`范围从`1`到`c`。 

对于每个三元组`(i, j, k)`，我们评估`d(i * j * k)`， 在哪里`d(x)`表示正因数的个数`x`。 最终答案是所有这些除数计数的总和，取模`2^30 = 1073741824`。 

约束足够小，迭代所有三元组是完全合理的。 由于每个变量最多`100`，三元组的总数最多为：$$100 \times 100 \times 100 = 10^6$$在 Python 中，在 2 秒的限制内进行 100 万次迭代就可以了。 真正的挑战是我们如何计算每个产品的除数计数。 

最大可能的乘积为：$$100 \times 100 \times 100 = 10^6$$一个简单的除数计数例程，用于检查来自的所有整数`1`到`n`需要大约`10^6`最坏情况下每个查询的操作数。 对另外一百万种产品重复此操作将爆炸至大约`10^{12}`的操作，远远超出了极限。 

重要的观察是许多产品重复。 例如，`2 * 3 * 4`和`1 * 6 * 4`两者都产生`24`。 如果我们计算除数计数`24`一旦并存储它，以后的每次出现都会变成 O(1) 查找。 

还有一些微妙的边缘情况可能会悄然破坏粗心的实现。 

考虑最小的输入：```
1 1 1
```唯一的产品是`1`， 和`d(1) = 1`。 一些除数计数实现意外返回`0`为了`1`因为他们假设每个数字都有一个质因数。 

使用平方根迭代计算除数时会出现另一个容易出现的错误。 例如：```
1 1 4
```产品有`1, 2, 3, 4`，其除数计数为`1, 2, 2, 3`。 

如果我们通过迭代来计算除数`sqrt(n)`并添加`2`对于每对约数，我们必须仔细对待完美平方。 为了`4`，除数对`(2,2)`应该只贡献一次。 忘记这一点会产生`4`而不是`3`。 

另一个陷阱是每次出现相同的产品时重新计算除数计数。 有输入：```
100 100 100
```许多产品重复率很高。 没有记忆的解决方案仍然执行数百万次昂贵的除数计算，并且存在超时的风险。 

## 方法

 最直接的解决方案是迭代每个三元组`(i, j, k)`，计算乘积`x = i * j * k`，然后计算`d(x)`通过检查每个整数`1`到`x`。 

这在逻辑上是有效的，因为除数的定义很简单：每个整数除`x`为计数贡献 1。 问题在于规模。 产品最多有 100 万个，每个除数计算最多可以扫描 100 万个数字。 最坏的情况大致变成：$$10^6 \times 10^6 = 10^{12}$$这是没有希望的。 

我们可以通过使用平方根属性来改进除数计数。 除数成对出现。 如果`d`划分`n`， 然后`n/d`也分`n`。 我们只需要测试最多的数字`sqrt(n)`。 

例如，除数`36`显示为：$$(1,36), (2,18), (3,12), (4,9), (6,6)$$仅检查最多`6`就足够了。 

这减少了一个除数计算`O(n)`到`O(sqrt(n))`。 由于最大的产品是`10^6`，现在每个除数计数的成本约为`1000`迭代。 经过一百万个三元组，这大约变成`10^9`操作，在Python中仍然太慢。 

关键的观察是不同产品的数量是有限的。 每个产品都介于`1`和`10^6`。 我们不会重复重新计算除数计数，而是缓存它们。 

当我们第一次遇到一个乘积时，我们使用平方根迭代计算它的除数计数并存储结果。 未来的每一次发生都会变成一次恒定时间的查找。 

这将昂贵的重复工作转变为一次性的预处理效果。 由于除数计数最多为`10^6`当每个不同值只执行一次时，成本足够低，解决方案很容易通过。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(abc × n) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(abc + U√U) | O(abc + U√U) | O(U) | 已接受 |

 这里，`U`是最大可能的乘积，至多`10^6`。 

## 算法演练

 1. 读取整数`a`,`b`， 和`c`。 
2. 创建字典或数组来存储除数计数。 

同一产品出现多次，因此缓存可以避免重复工作。 
3. 迭代所有三元组`(i, j, k)`。 

由于每个界限最多是`100`，迭代总数是可控的。 
4. 计算乘积：$$x = i \times j \times k$$5.如果`x`之前尚未处理过，计算其除数计数。 

迭代`d`从`1`到`⌊√x⌋`。 

如果`d`划分`x`，那么：

 - 添加`2`如果`d`和`x/d`是不同的
 - 添加`1`如果`d*d == x`这可以正确计算除数对，而无需重复计算完全平方数。 
6. 存储除数计数`x`在缓存中。 
7. 将缓存的除数计数添加到运行答案中。 
8. 处理完所有三元组后，打印答案模数`1073741824`。 

### 为什么它有效

 对于每一个三元组`(i, j, k)`，算法准确计算出问题所需的值，即`d(i*j*k)`。 

除数计数例程是正确的，因为下面的每个除数`sqrt(n)`对应于上面的配对除数`sqrt(n)`。 完全平方在平方根本身贡献一个不成对的除数。 

记忆不会改变正确性。 它只是避免重新计算之前已经见过的产品的值。 每次查找都会返回与手动重新计算相同的除数计数。 

由于每个三元组都被处理一次并准确地贡献其除数计数，因此最终的总和是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1073741824

a, b, c = map(int, input().split())

cache = {}
answer = 0

for i in range(1, a + 1):
    for j in range(1, b + 1):
        for k in range(1, c + 1):
            x = i * j * k

            if x not in cache:
                divisors = 0
                d = 1

                while d * d <= x:
                    if x % d == 0:
                        if d * d == x:
                            divisors += 1
                        else:
                            divisors += 2
                    d += 1

                cache[x] = divisors

            answer += cache[x]

print(answer % MOD)
```这三个嵌套循环将每个有效的三元组恰好枚举一次。 由于边界仅是`100`，一百万次迭代是可以接受的。 

缓存存储按乘积值键控的除数计数。 这是关键的优化。 如果没有它，相同的除数计数将被重新计算多次。 

除数计数循环使用平方根方法。 条件`d * d <= x`保证我们检查所有可能的除数对。 

完全正方形分支很容易出错。 例如，当`x = 36`, 除数`6`与自身配对。 我们应该数一次，而不是两次。 

模数仅在最后应用。 Python 整数不会溢出，因此中间和是安全的。 在累加过程中应用模数也可以。

 ## 边缘情况

 考虑尽可能最小的输入：```
1 1 1
```该算法仅处理一个三元组：

 | 产品 | 除数 |
 | ---| ---|
 | 1 | 1 |

 除数循环运行`d = 1`。 自从`1 * 1 == 1`，该算法正确地仅添加一个除数而不是两个。 

最终答案：```
1
```现在考虑一个完美的正方形情况：```
1 1 4
```产品有`1, 2, 3, 4`。 

为了`4`，除数循环的行为如下：

 | d | d*d <= 4 | 4 % d == 0 | 贡献 |
 | ---| ---| ---| ---|
 | 1 | 是的 | 是的 | +2 |
 | 2 | 是的 | 是的 | +1 |

 总除数计数变为`3`，对应于`{1,2,4}`。 

一个粗心的实现总是会增加`2`对于除数对会错误地返回`4`。 

最后，考虑重复产品：```
2 2 2
```产品`4`出现三次。 第一次出现计算其除数计数并存储：```
cache[4] = 3
```接下来的两次出现立即重用缓存的值。 这避免了重复的平方根扫描，并使运行时间对于最大的输入来说足够快。
