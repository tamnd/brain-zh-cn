 ## 解决方案
 ## 问题理解

 爱丽丝和鲍勃玩多组数字。 Alice 和 Bob 交替从数组中删除元素，Alice 首先移动。 不同之处在于，每当 Alice 删除一个值时，她也会将其保留在她的个人数组中`c`，而 Bob 只是删除一个值。 

当所有元素都被移除后，游戏的分数就是以下的 MEX：`c`，表示Alice收集的值中未出现的最小非负整数。 

Alice 希望这个 MEX 尽可能大。 鲍勃希望它尽可能小。 我们必须在假设两名选手都发挥完美的情况下确定最终得分。 

数组值始终介于`0`和`n-1`，所有测试用例的元素总数最多为`2 · 10^5`。 这立即表明任何二次方都太昂贵了。 执行与元素数量成正比的工作的解决方案，或者也许`n log n`，很容易足够快。 

棘手的部分是这是一个游戏。 一个幼稚的实现可能会尝试逐步模拟最佳游戏，但可能的游戏状态数量呈指数级增长。 真正的任务是了解 Alice 可以强行进入她的集合中的哪些值以及 Bob 可以阻止哪些值。 

有几种边缘情况很容易误判。 

考虑：```
2
1 1
```没有`0`根本不。 爱丽丝永远无法获得`0`，所以答案是`0`。 

考虑：```
4
0 1 2 3
```每个所需的值都只出现一次。 爱丽丝拿走了其中一张，鲍勃立即删除了另一张。 鲍勃可以摧毁未来 MEX 的一种缺失成分，所以答案只有一个`1`， 不是`4`。 

考虑：```
4
0 0 1 1
```每个重要值出现两次。 Alice 可以拿走一份副本，而 Bob 则可以删除另一份。 两个都`0`和`1`生存下来，所以答案就变成了`2`。 

一个常见的错误是计算原始数组的普通 MEX。 游戏是关于爱丽丝可以保证收集哪些价值，而不是哪些价值仅仅存在。 

## 方法

 蛮力观点是将游戏视为极小极大搜索。 在每个状态中，Alice 选择一个元素来最大化最终的 MEX，而 Bob 选择一个元素来最小化它。 这是正确的，因为它直接模拟了最佳游戏。 

不幸的是，即使是谦虚的`n`，状态的数量变得巨大。 每一步都会产生多种可能性，使得复杂性基本上呈指数级增长。 和`n`最多`2 · 10^5`，这是完全不可行的。 

关键的观察结果是只有值的频率才重要。 

假设我们关注某个数字`x`。 

如果`x`根本不存在，爱丽丝永远无法获得它。 

如果`x`只出现一次，那么获得该唯一副本的玩家决定是否`x`将属于爱丽丝的收藏。 鲍勃总是可以针对这些脆弱的价值观。 

如果`x`至少出现两次，爱丽丝就有了更多的保护。 即使 Bob 删除了一份副本，另一份仍然可用。 

至少要进入最终的MEX`k`，爱丽丝必须获得其中的每个值`0`通过`k-1`。 

Bob 的最佳策略是尽早创建缺失值。 值与频率`1`是唯一他可以通过获取其唯一副本来永久销毁号码的地方。 

这导致了非常简单的表征。 

扫描值来自`0`向上。 

如果某个值从未出现，该值将立即成为答案。 

在出现的值中，准确计算有多少个值具有频率`1`。 

此计数达到的第一个值`2`也是答案。 

为什么？ Alice 首先移动，因此在所有单例值中，在 Bob 销毁另一个单例之前，她最多可以确保其中一个值。 第二个单例成为爱丽丝收藏中第一个不可避免的缺口。 

这将游戏问题转化为频率计数问题。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算数组中每个值的出现频率。 
2. 初始化计数器`single = 0`。 这将跟踪到目前为止看到的有多少值恰好出现一次。 
3. 扫描值`0`向上。 
4. 当前值是否有频率`0`，立即返回该值。 

Alice 无法收集缺失值，因此它自动成为 MEX。 
5. 当前值是否有频率`1`, 增量`single`。 
6. 如果`single`变成`2`，返回当前值。 

Alice 可以保证最多拥有一个单例值。 第二个单例创建了 Bob 可以强制使其不存在于 Alice 集合中的第一个值。 
7. 扫描总是终止，因为值被限制在范围内`[0, n-1]`，最终超出现有频率的一些值将有意义`0`。 

### 为什么它有效

 对于频率至少为 2 的每个值，在 Alice 有机会获得一份副本之前，Bob 无法完全删除该值。 这样的值是安全的。 

频率恰好为 1 的值是脆弱的。 Bob 可以通过获取单例的唯一副本来永久消除该单例。 由于 Alice 首先移动，因此她最多可以保护对 MEX 重要的不断增加的值序列中的一个单值。 一旦出现两个单例值，Bob 总是可以阻止其中之一进入 Alice 的集合。 不可避免的情况下，最小值正是最终的 MEX。 

第一个不存在的值也会立即确定 MEX，因为 Alice 无法收集不存在的东西。 

这两个条件完全体现了最佳游戏的特征。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    answers = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        freq = [0] * (n + 1)
        for x in a:
            freq[x] += 1

        single = 0

        for mex in range(n + 1):
            if freq[mex] == 0:
                answers.append(str(mex))
                break

            if freq[mex] == 1:
                single += 1

            if single == 2:
                answers.append(str(mex))
                break

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```频率数组是核心数据结构。 由于每个值都满足`0 ≤ a[i] < n`，一个大小的数组`n + 1`就足够了。 

扫描按升序进行，因为 MEX 取决于第一个有问题的值。 当我们遇到缺失值时，答案就固定了，我们就停下来。 

这`single`计数器跟踪出现了多少个脆弱值。 第一个单例可以由 Alice 保护。 第二个单例是鲍勃可以强制间隙的地方，因此我们立即返回。 

一个微妙的细节是扫描`n`。 即使输入值严格小于`n`，答案可以是`n`。 例如：```
0 1 2 3
```有普通MEX`4`。 仅使用大小的频率数组`n`就会错过这个可能性。

 ### 示例 1

 输入：```
4

```频率表：

 | 价值| 频率| 单次计数 | 行动|
 | ---| ---| ---| ---|
 | 0 | 2 | 0 | 继续 |
 | 1 | 2 | 0 | 继续 |
 | 2 | 0 | 0 | 答案 = 2 |

 输出：```
2
```这两个重要值都出现两次，因此 Bob 无法完全阻止其中任何一个。 第一个缺失值是`2`，成为最终的 MEX。 

### 示例 2

 输入：```
4
0 1 2 3
```频率表：

 | 价值| 频率| 单次计数 | 行动|
 | ---| ---| ---| ---|
 | 0 | 1 | 1 | 继续 |
 | 1 | 1 | 2 | 答案 = 1 |

 输出：```
1
```每个值都是一个单例。 爱丽丝只能保护其中之一。 一旦第二个单例出现，Bob 就可以强制在其中添加一个缺失值`{0,1}`，使 MEX 等于`1`。

 ## 边缘情况

 考虑：```
1
2
1 1
```频率`0`已经为零。 在扫描过程中，算法立即停止在值`0`并返回`0`。 Alice 无法收集不存在的值，因此 MEX 必须是`0`。 

考虑：```
1
4
0 1 2 3
```扫描看到频率`1`为了价值`0`， 制作`single = 1`。 然后它会看到频率`1`为了价值`1`， 制作`single = 2`，并返回`1`。 这说明了鲍勃可以在爱丽丝收集所有单例值之前销毁其中一个值的事实。 

考虑：```
1
6
0 0 1 1 2 2
```所有频率高达`2`至少有两个。 单例计数器永远不会增加。 扫描达到价值`3`，其频率为零，并返回`3`。 多个副本可以保护每个所需的值免受鲍勃的干扰。 

考虑：```
1
5
0 0 1 2 2
```扫描过程：

 | 价值| 频率| 单次计数 |
 | ---| ---| ---|
 | 0 | 2 | 0 |
 | 1 | 1 | 1 |
 | 2 | 2 | 1 |
 | 3 | 0 | 1 |

 第一个缺失值是`3`，所以答案是`3`。 只有一个单例，Alice 可以保护它，因此 Bob 无法强制较早的间隙。
