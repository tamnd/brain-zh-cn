 ## 解决方案
 ## 问题理解

 我们有`m`公司和`n`未来的日子。 对于每家公司，我们每天都知道其股价。 输入每行存储一家公司，因此每行包含该公司从第一天到当天的价格`n`。 

我们从`d`在第一个已知日期之前磅。 一天内，价格不会发生变化，我们可以进行任意数量的交易。 由于样本本身需要投资非整数数量的股票，因此我们可以将我们的资金视为连续可分：如果我们有`x`英镑和股票成本`p`，我们可以把所有`x`磅入`x / p`股票。 在一天结束时`n`，我们想要最大可能的现金价值。 

无限制的当日交易的关键后果是我们不需要记住复杂的投资组合。 假设我们有`x`从一天开始过渡时的磅数`i`今天`i+1`，以及公司`j`成本`p`当天`i`和`q`当天`i+1`。 将一切投资于该公司将改变我们的财富`x`到`x * q / p`。 最好的公司就是比例最大的公司`q / p`。 将钱保留为现金也是一种选择，但比例`1`。 

天数最多为50天，公司数量最多为1000家。`O(nm)`算法最多执行约 50,000 次比率比较，完全在一秒的限制内。 尝试公司所有可能的选择顺序的策略会呈指数级增长`n`，因此即使是 50 天这一相对较小的界限也使得这种枚举变得不可能。 输入本身仅包含`nm <= 50,000`价格，因此存储完整的矩阵并不昂贵。 

在某些情况下，粗心的实施可能会悄无声息地失败。 首先，当只有一天时，根本不存在价格转变。 例如，```
1 1 25.00
7.50
```有答案`25.00`。 没有机会将初始资金变成更大的金额，因为最后一天也是第一个观察到的日子。 盲目应用一个转换的实现将执行一项不存在的操作。 

第二，我们不需要投资。 考虑```
2 1 100.00
5.00 4.00
```唯一的股票贬值，所以正确答案是`100.00`。 总是购买股票的解决方案将错误地获得`80.00`。 现金资产有效贡献了乘数`1`，所以每个每日乘数必须至少为`1`。 

第三，最好的公司可以日复一日地改变。 例如，```
3 2 10.00
1.00 10.00 1.00
1.00 1.00 10.00
```第一次转型最好通过公司 1，将资金乘以`10`。 第二次转型最好通过公司 2 进行，将其乘以另一个公司`10`, 给予`100.00`。 在整个期间选择一家公司的解决方案将错过这种可能性。 

## 方法

 直接蛮力策略可以在连续几天之间的每次转换中尝试每种可能的股票选择。 对于每个完整的序列，我们将当前金额乘以相应的价格比率并保留最大的结果。 我们还需要保留现金的选择，因此每次过渡最多有`m + 1`选择。 

这种蛮力是正确的，因为每个候选序列都描述了在每个日常间隔内投资当前财富的可能方式。 问题在于序列的数量。 有`(m + 1)^(n - 1)`其中，评估一个序列需要`O(n)`工作。 在最坏的情况下这是`O(n(m + 1)^(n - 1))`。 和`n = 50`和`m = 1000`，大致就是`49 * 1001^49`， 大约`5 * 10^148`基本操作，这是完全不可行的。 

消除指数因子的观察结果是不同的跃迁不会相互干扰。 一旦我们到达特定的一天`x`磅，所有可能的历史记录都可以用这个数字来概括。 对于下一次过渡，唯一的问题是哪种资产提供从今天的价格到明天的价格的最大乘数。 由于无限制的当天交易让我们可以出售旧的股份并立即购买新的股份，因此更换公司的成本不超过其上市价格。 

对于公司`j`，当天的乘数`i`今天`i+1`是`price[i+1][j] / price[i][j]`。 

我们对所有公司及以上公司取该比率的最大值`1`现金。 然后我们将当前财富乘以该最大值。 对所有人独立重复此操作`n - 1`过渡给出了最优值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(n(m+1)^(n-1))`|`O(n)`| 太慢了|
 | 最佳 |`O(nm)`|`O(nm)`| 已接受 |

 ## 算法演练

 1.读取天数`n`, 企业数量`m`，以及初始金额`d`。 存储`m`价格行，因为每次转换都需要每个公司连续两天的价格。 
2. 将当前金额设置为`d`。 在处理任何转换之前，这正是第一天开始时可用的金额。 
3. 对于每一对连续的天`i`和`i + 1`，检查每家公司。 如果它的价格是`p = price[i][j]`和`q = price[i+1][j]`，计算乘数`q / p`。 
4. 开始最佳的过渡乘数`1.0`。 这意味着将所有钱都保留为现金。 每当股票提供更大的乘数时就更换它。 
5. 将当前金额乘以最佳乘数。 这给出了第二天可以使用的最大金额，因为所有资金都可以转换为针对该特定过渡的表现最佳的资产。 
6. 处理完最终转换后，打印结果金额（小数点后两位）。 什么时候`n = 1`，循环迭代次数为零，因此原始金额打印不变。 

### 为什么它有效

 维持不变式`money`是在利用截至当天的所有盈利机会后当天可用的最大现金金额。 考虑下一个转变。 现在可用的任何资金都可以保留为现金，从而保留一个乘数`1`，或完全转换为一家公司的股票。 如果公司`j`选择了，每一磅就变成`price[i+1][j] / price[i][j]`第二天磅。 由于允许任意当日交易，因此可以出售任何先前的股票，并且可以将整个投资组合转移到比率最大的公司中。 因此，第二天可能的最佳财富恰好是`money * max(1, max_j(price[i+1][j] / price[i][j]))`。 每次转换时都会保留不变式，因此在最后一天之后，计算出的量是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, money = input().split()
    n = int(n)
    m = int(m)
    money = float(money)

    prices = [list(map(float, input().split())) for _ in range(m)]

    for day in range(n - 1):
        best_ratio = 1.0

        for company in range(m):
            ratio = prices[company][day + 1] / prices[company][day]
            if ratio > best_ratio:
                best_ratio = ratio

        money *= best_ratio

    print(f"{money:.2f}")

if __name__ == "__main__":
    solve()
```前三个值是从第一行解析的，其中`n`和`m`转换为整数，初始资本转换为浮点数。 价格存储为`prices[company][day]`，直接匹配面向行的输入。 

外循环从一天开始运行`0`通过一天`n - 2`。 这正好对应于`n - 1`连续几天之间的过渡。 使用`range(n - 1)`也正是这使得`n = 1`案例会自动工作，因为没有任何转换。 

对于每个转变，`best_ratio`开始于`1.0`，不在`0`。 这代表了不采取任何行动并将资金保留为现金的选择。 由于每个股票价格都是正数，因此除以价格总是安全的。 

该比率是在更新之前计算的`money`，因此每家公司都使用相同的启动资金进行转型比较。 检查完所有公司后才更新金额，相当于选择最好的公司并将其全部投入。 

Python 的浮点运算在这里就足够了，因为所需的输出容差是`0.01`，而答案最多保证是`10^9`。 Python 也不存在固定宽度整数溢出问题，尽管该解决方案无论如何都不需要大整数。 格式化为`:.2f`产生所需的两位小数。 

## 工作示例

 ### 示例 1

 输入是```
4 2 10.00
1.02 1.00 1.00 1.00
4.37 4.81 5.32 6.06
```两行是两家公司的价格历史记录。 

| 过渡 | 公司1比率| 公司2比率| 最佳乘数 | 钱|
 | ---| ---| ---| ---| ---|
 | 第 1 天 → 第 2 天 |`1.00 / 1.02 ≈ 0.9804`|`4.81 / 4.37 ≈ 1.1007`|`1.1007`|`11.007`|
 | 第 2 天 → 第 3 天 |`1.00 / 1.00 = 1`|`5.32 / 4.81 ≈ 1.1060`|`1.1060`|`12.174`|
 | 第 3 天 → 第 4 天 |`1.00 / 1.00 = 1`|`6.06 / 5.32 ≈ 1.1391`|`1.1391`|`13.873`|

 最终值四舍五入为`13.87`。 该跟踪还说明了为什么不需要存储实际的股份数量。 每次转型后，当前的全部财富都可以再次被视为现金，然后为下一次转型进行最佳再投资。 

### 构造示例 2

 考虑```
3 2 10.00
1.00 10.00 1.00
1.00 1.00 10.00
```| 过渡 | 公司1比率| 公司2比率| 最佳乘数 | 钱|
 | ---| ---| ---| ---| ---|
 | 第 1 天 → 第 2 天 |`10 / 1 = 10`|`1 / 1 = 1`|`10`|`100`|
 | 第 2 天 → 第 3 天 |`1 / 10 = 0.1`|`10 / 1 = 10`|`10`|`1000`|

 答案是`1000.00`。 最佳策略在两次转型之间改变公司。 这证实了该算法不会在整个时期内只选择一只股票。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(nm)`| 有`n - 1`转换，并且每个转换都会检查所有`m`公司。 |
 | 空间|`O(nm)`| 完整的价格矩阵包含`m * n`浮点值。 |

 在最多 50 天和 1000 家公司的情况下，该算法执行的比率计算少于 50,000 次。 价格矩阵还包含最多 50,000 个值，因此运行时间和内存使用量都很容易在一秒和 256 MB 的限制之内。

 ## 边缘情况

 当只有一天时，就没有投资区间。 为了```
1 1 25.00
7.50
```循环结束`range(n - 1)`变成`range(0)`， 所以`money`遗迹`25.00`输出是`25.00`。 这避免了将第一天与不存在的第二天进行比较的常见错误。 

当每只可用股票都贬值时，现金必须击败所有股票。 为了```
2 1 100.00
5.00 4.00
```唯一有比率的股票`4 / 5 = 0.8`，而现金有比率`1`。 算法初始化`best_ratio`到`1.0`，因此转变使财富处于`100.00`。 总是购买最好的股票而不考虑现金的贪婪实施会错误地减少资本。 

当最佳公司发生变化时，算法会在每次转变后刻意重新评估所有公司。 在```
3 2 10.00
1.00 10.00 1.00
1.00 1.00 10.00
```第一次转换选择公司 1 并将资金乘以`10`。 由此产生的`100.00`然后被视为第二次转型的可用资本，其中公司 2 的比率`10`。 最终值为`1000.00`。 前一个选择不会限制下一个选择，因为当日买卖不受限制。 

如果所有价格都相等，则每个库存比率恰好是`1`，所以首都永远不会改变。 为了```
3 2 123.45
5.55 5.55 5.55
2.00 2.00 2.00
```每个转变都有最佳乘数`1`，生产`123.45`自始至终。 这也检查了该算法不会从重复的同日交易中创造人为利润。 

最后，即使存在盈利机会，零初始资本也是无害的。 为了```
2 1 0.00
1.00 10.00
```该股票提供的乘数为`10`， 但`0 * 10`仍然是`0`。 答案是`0.00`。 该算法独立于资本数量计算最佳乘数，然后将其应用于当前财富，因此这种边界情况不需要特殊处理。
