 ## 解决方案
 ## 问题理解

 我们反复掷骰子`k`面孔。 一次成功的滚动表明`1`，我们一看到游戏就结束了`n`连续滚动成功。 每卷花费 1 英镑，因此所需的奖品正是预期的卷数，直到第一次出现`n`连续的。 

输入包括`k`，骰子上的面数，以及`n`，连续条纹所需的长度。 输出是预期的卷数，绝对或相对误差最多为`10^-4`。 官方的限制是`3 <= k <= 20`和`1 <= n <= 5`。 

小上限为`n`可能会建议进行模拟或基于状态的动态程序，但我们需要的数量是精确的期望，而不是特定的随机实验。 模拟可能需要大量的掷骰，并且只能得到近似的答案。 有用的观察是每次掷骰子成功的概率固定为`1/k`，过去影响我们未来的唯一信息是完全由 1 组成的后缀的当前长度。 

有几种边界情况很容易处理不当。 为了`n = 1`，一个人已经完成了游戏。 例如，使用输入`3 1`，预期的卷数是`3`，因为每次掷骰都有概率`1/3`结束游戏。 假设始终存在非空中间条纹状态的递归可能会意外地返回错误值。 

另一个常见的错误是在获胜掷骰后计算掷骰数而不是包括它。 为了`k = 6, n = 2`，正确答案是`42`， 不是`41`，因为获胜卷本身的成本为 1 英镑。 样本证实了这个值。 

第三个问题是忘记了延长连续记录的失败尝试会完全重置当前的连续记录。 和`k = 3, n = 2`，一个序列如`1, 1`两卷后完成，同时`1, 2, 1, 1`四点后结束。 之后`2`, 较早的`1`无法为新的连胜做出贡献。 

## 方法

 一个直接的蛮力想法是生成可能的骰子序列并确定每个序列何时首先包含`n`连续的。 这在概念上是正确的，因为每个有限序列都有一个已知的概率，并且在所有可能的结果上平均其停止时间给出了期望的期望。 问题是该过程没有固定的最大长度。 序列可以避免任意多次滚动的目标条纹，因此穷举枚举没有有限的最坏情况停止界限。 即使我们人为地停下来`L`卷，有`k^L`要检查的序列，这几乎立即变得不可行。 

我们可以使用当前的条纹长度来描述该过程。 让`E_i`是当当前后缀恰好包含时所需的额外卷的预期数量`i`连续的，其中`0 <= i < n`。 来自州`i`，下一卷花费一卷。 有概率`1/k`，这是另一个，让我们不得不说`i + 1`。 有概率`(k - 1)/k`，它不是一，并且条纹重置为状态`0`。 

因此，`E_i = 1 + (1/k) E_{i+1} + ((k-1)/k) E_0`和`E_n = 0`。 

关键的简化是我们实际上不需要以数值方式求解所有这些方程。 从最后一个状态开始向后代入会产生几何和。 结果是`E_0 = (1 - (1/k)^n) / ((1 - 1/k)(1/k)^n)`。 

分子和分母乘以`k^n`给出更清晰的整数表达式`E_0 = (k^(n+1) - k) / (k - 1)`。 

例如，与`k = 6`和`n = 2`，这给出了`(6^3 - 6) / 5 = 210 / 5 = 42`。 

答案实际上是一个整数，代表所有有效的整数值`k`和`n`，因此浮点运算是不必要的。

 | --- | --- | --- | --- |
 | 蛮力 | 无界，`O(k^L)`对于地平线`L`|`O(L)`| 太慢了|
 | 最佳|`O(1)`|`O(1)`| 已接受 |

 ## 算法演练

 1. 阅读`k`和`n`。 掷出 1 的概率为`1/k`，而滚动其他任何东西的概率是`(k-1)/k`。 
2. 根据当前连续 1 后缀的长度对过程进行建模。 如果当前后缀有长度`i`, 1 将其增加到`i+1`，而任何其他值会将其重置为零。 这捕获了过去可能影响剩余等待时间的所有信息。 
3.让`E_i`表示状态的预期剩余卷数`i`。 终端状态是`E_n = 0`，因为已经获得了所需的连胜。 
4. 对于每个非终结状态，写出一步期望`E_i = 1 + E_{i+1}/k + (k-1)E_0/k`。 

这`1`说明我们即将制作的卷。 剩下的两个术语描述了接下来两种可能的状态。 
5. 向后求解递推式。 重复替换表示`E_0`就其本身和几何序列而言。 结果方程简化为`E_0 = (k^(n+1) - k)/(k-1)`。 
6. 使用整数算术计算该表达式并打印它。 允许的最大答案最多是`10^9`，因此 Python 的整数算术可以轻松处理计算。 

### 为什么它有效

 国家`i`始终精确地表示紧邻下一卷之前的连续数。 这已经足够了，因为一旦知道当前后缀长度，旧的卷对未来的卷就没有影响。 从每个状态，循环都会考虑每一个可能的下一个结果，并为下一个掷骰精确地添加一个。 自从`E_n = 0`，求解递推式给出了每个状态的预期停止时间，包括初始状态`E_0`。 封闭形式只是这些期望方程的精确解，因此算法返回所需的期望滚动次数，而不是基于随机模拟的估计。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    k, n = map(int, input().split())

    answer = (k ** (n + 1) - k) // (k - 1)
    print(f"{answer:.2f}")

if __name__ == "__main__":
    solve()
```程序读取这两个参数并直接评估由递归获得的封闭形式。 不需要构造各个条纹状态，因为递归已经在代数上得到了简化。 

指数是`n + 1`， 不是`n`。 这是一种常见的相差一错误。 为了`n = 1`，公式变为`(k^2-k)/(k-1) = k`，这正是一次成功掷骰的预期等待时间。 

减法也是`k`, 给予`k^(n+1) - k`。 仅使用`k^(n+1)`会产生不正确的结果，即使对于大值来说它可能看起来很接近。 

整数除法是安全的，因为表达式始终是整数。 更重要的是，它避免了在格式化之前引入浮点舍入。 输出使用两位小数，完全符合要求`10^-4`宽容。

## 测试用例```python
import sys
import io

def solve():
    k, n = map(int, input().split())
    answer = (k ** (n + 1) - k) // (k - 1)
    print(f"{answer:.2f}")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
assert run("6 2\n") == "42.00", "sample 1"

# Minimum k and minimum n
assert run("3 1\n") == "3.00", "single one on a 3-sided die"

# Maximum k and maximum n
assert run("20 5\n") == "3368420.00", "maximum constraints"

# Two-sided streak with the smallest possible die
assert run("3 2\n") == "6.00", "short streak"

# Boundary case n = 1 with a larger die
assert run("20 1\n") == "20.00", "single one on a 20-sided die"

 ## 边缘情况

 对于`3 1`，目标只是第一个等于 1 的掷骰。 公式给出`(3^2 - 3)/(3-1) = 3`，所以输出是`3.00`。 无意中使用的解决方案`k^n`而不是`k^(n+1)`这种情况会立即失败。 

为了`6 2`，目标是两个连续的。 公式给出`(6^3 - 6)/5 = 42`，所以输出是`42.00`。 此案例发现了在对成功的掷骰进行充电之前停止计数的错误，因为期望包括创建最终连胜的掷骰。 

为了`3 2`，期望值为`(3^3 - 3)/2 = 12/2 = 6`。 一个有用的手动跟踪是，该过程从状态零开始，一个接一个地移动到一个状态，一个接一个状态到达最终状态，并在任何非一之后返回到零。 重复包括两个转变，因此重复失败的尝试被考虑在内，而不是将每对卷视为独立的试验。 

为了`20 5`，答案是`(20^6 - 20)/19 = 3,368,420`。 这是给定约束的最大角，并说明了为什么模拟单个滚动是计算期望的糟糕方法。 封闭形式可以立即得出答案，而实际的随机过程可能需要数百万次滚动才能出现所需的条纹。
