 ## 解决方案
 ## 问题理解

 我们需要准确地制作`d`美元的零钱。 可用的硬币面额是以下的每个整数`a`通过一些上限`b`，包括在内，并且我们可以多次使用任何面额。 任务是找到尽可能小的`b`为此`d`可以表示为这些硬币的总和。 

输入包含`a`和`d`， 和`1 <= a <= d <= 10^9`。 由于这些值可以达到 10 亿，因此检查可能值的线性数量的算法对于 1 秒的限制来说过于昂贵。 我们需要将问题简化为常数时间算术，而不是一一尝试候选值。 

第一个边界情况是`a = d`。 唯一的办法就是制作`d`就是使用有价值的硬币`d`，所以答案一定是`d`。 例如，`10 10`给出`10`。 假设至少需要两个硬币的粗心方法可能会错误地返回较小的值。 

另一个小案例是`a = 1`。 例如，`1 7`有答案`1`，因为硬币有价值`1`独自一人就可以赚到每一笔正数。 搜索从`a + 1`会立即错过这个。 

案例中`d`可以整除`a`也很重要。 为了`6 18`, 三枚等值硬币`6`已经制定了目标，所以`b = 6`。 基于舍入的解决方案`d / floor(d / a)`浮点运算不正确可能会在大值时引入精度问题，因此最好采用整数上限除法。 

## 方法

 直接的方法是尝试所有可能的大面额`b`，开始于`a`。 对于每个候选人，我们可以确定是否`d`可以使用来自的硬币形成`a`通过`b`。 这是正确的，因为我们按升序检查候选者，因此第一个可行的必然是最小值。 

问题是`b`可以大到`d`， 和`d`可以是`10^9`。 在最坏的情况下，这意味着粗略地检查`10^9`候选人。 即使可以在恒定时间内测试每个候选者，也需要大约 10 亿次操作，这对于 1 秒的时间限制来说是远远不合适的。 

有用的观察来自于固定硬币的数量而不是固定最大面额。 假设我们准确地使用`k`硬币。 可能的最小总和是`ka`，因为每枚硬币至少`a`。 最大可能的总和是`kb`，因为每枚硬币最多`b`。 

更重要的是，因为每个教派之间`a`和`b`存在，之间的每个整数和`ka`和`kb`是可以实现的。 因此`d`可以精确地形成`k`硬币恰好在`ka <= d <= kb`。 

第一个不等式给出`k <= floor(d / a)`。 让`q = floor(d / a)`。 

如果我们最多可以使用`q`硬币，然后选择`q`硬币给了我们下限最大可能的灵活性，因为`qa <= d`。 我们只需要`b`足够大`q`硬币可以到达`d`，这意味着`qb >= d`。 

因此尽可能最小`b`是`ceil(d / q)`，

在哪里`q = floor(d / a)`。 

没有理由考虑少于`q`硬币。 如果`k < q`， 然后`ceil(d / k) >= ceil(d / q)`，因此需要较少的硬币只能使必要的最大面额更大或相等。 暴力搜索可能的`b`因此被减少到两个整数除法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(d - a + 1) | O(1) | O(1) | 太慢了|
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`a`和`d`。 这些是最低可用硬币价值和目标金额。 
2. 计算`q = d // a`。 这是至少有价值的最大硬币数量`a`这可能适合于总和`d`。 
3. 计算最小面额界限，使得`q`硬币到达`d`。 我们需要`q * b >= d`，因此使用整数上限除法：`b = (d + q - 1) // q`。 
4. 打印`b`。 自从`q`是最大可行的硬币数量，该值是可能的最小面额。 

### 为什么它有效

 让`q = floor(d / a)`。 自从`qa <= d`， 使用`q`当所有硬币都有价值时，硬币不会超过目标`a`。 我们需要那些`q`硬币能够达到`d`，这需要`qb >= d`。 

因为可用面额形成了完整的整数区间`a`到`b`，之间的每个总和`qa`和`qb`完全可以通过以下方式实现`q`硬币。 因此`b = ceil(d / q)`就足够了。 

对于任何较少数量的硬币`k < q`，达到`d`需要`b >= ceil(d / k)`。 自从`k < q`，我们有`ceil(d / k) >= ceil(d / q)`。 因此不更小`b`可以使用更少的硬币。 计算值既可行又最小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

a, d = map(int, input().split())

q = d // a
b = (d + q - 1) // q

print(b)
```价值`q`是用整数除法计算的，所以它恰好是`floor(d / a)`。 自从`a <= d`,`q`总是至少`1`，这使得后续的划分是安全的。 

表达式`(d + q - 1) // q`执行上限除法而不进行浮点运算。 这很重要，因为输入可以包含最多的值`10^9`，整数算术给出了精确的结果，无需考虑舍入问题。 

Python 整数也具有任意精度，因此不存在整数溢出问题。 在具有固定宽度整数类型的语言中，对于标准 64 位整数的这些约束，相同的公式仍然是安全的。

 ## 边缘情况

 对于`a = d`， 考虑`10 10`。 计算得出`q = 10 // 10 = 1`， 其次是`b = ceil(10 / 1) = 10`。 结果是正确的，因为可以实现目标的唯一可用面额是`10`本身。 该算法不会意外地假设需要多个硬币。 

为了`a = 1`， 考虑`1 7`。 我们得到`q = 7`， 所以`b = ceil(7 / 7) = 1`。 这表示单一面额`1`就足够了。 确实，七枚硬币值钱`1`准确地制定目标。 这种情况也证实了答案可以等于最小可能的输入值`a`。 

对于完全可分的目标，考虑`6 18`。 这里`q = 18 // 6 = 3`， 和`b = ceil(18 / 3) = 6`。 三枚价值不菲的硬币`6`制作`18`，因此不需要更大的面额。 计算正好落在`a`，这是可能的最小答案。 

对于不可分割的目标，请考虑`3 10`。 我们有`q = 10 // 3 = 3`。 必须达到三枚硬币`10`，因此最大面额必须满足`3b >= 10`, 给予`b = 4`。 实际公式得出`(10 + 3 - 1) // 3 = 12 // 3 = 4`， 不是`3`。 有面额`3`和`4`，目标是`3 + 3 + 4 = 10`。 这就是暴露普通楼层划分错误使用的案例。 

最后，考虑最大目标`a = 500000000`,`d = 1000000000`。 我们得到`q = 2`， 和`b = ceil(1000000000 / 2) = 500000000`。 两枚价值不菲的硬币`500000000`准确地制定目标。 即使在最大输入规模下，计算也保持恒定时间。
