 ## 解决方案
 ## 问题理解

 我们被要求构造一种特殊类型的无向图。 该图有 _n_ 个顶点和一个参数 _p_，并且它必须满足两个全局条件。 首先，边的总数正好是 2_n_ + _p_。 其次，_k_ 个顶点的子图不能有超过 2_k_ + _p_ 条边。 禁止同一对顶点之间存在自环和多重边。 

实际上，输入给出了几个测试用例，每个测试用例指定一个_n_和一个_p_，输出应该是满足条件的图的边列表。 每条边都表示为对应于它所连接的顶点的一对整数。 对 _n_ （最多 24）的限制以及总边数总是适度的事实表明我们可以建设性地进行推理，而不是依赖于繁重的组合搜索。 解决方案的存在保证还暗示存在用于生成这些图的简单、可重复的模式。 

微妙之处来自于子图条件。 对于小_k_，添加太多边可能会违反规则。 例如，当 n = 6 且 p = 0 时，我们正好需要 12 条边。 将每个顶点相互连接的简单方法会给出 15 条边，这违反了子图规则，即使总边数几乎是正确的。 因此，该算法必须小心地添加边，以便任何顶点子集中的边计数永远不会超过允许的阈值。 

## 方法

 暴力方法将枚举 _n_ 个顶点上所有可能的边集，并根据子图条件检查每个候选边。 生成所有可能的图需要考虑 m 个边的 C(n(n−1)/2, m) 个边组合，即使对于 n = 24，这也是爆炸性的。检查子图条件天真地涉及检查所有 2^n 子集，使得暴力方法完全不可行。 

关键的见解来自于对公式的检查。 2_n_ + _p_ 边图可以解释为“近 2-正则”结构：每个顶点应与大约 2 条边相关，并仔细添加 _p_ 额外边。 如果我们首先以循环方式将每个顶点连接到其接下来的两个邻居，我们保证每个小顶点子集包含不超过 2_k_ 条边。 这是因为 k 个顶点的连通循环在本地最多贡献 2_k_ 个边。 

一旦构建了基本循环，任何额外的 _p_ 边都可以在尚未完全连接的顶点之间顺序添加，而不会违反子图边界。 因为问题保证了解的存在，所以我们总是可以系统地选择这样的对。 这将构造简化为简单的确定性模式：用和弦形成一个循环，然后散布剩余的边缘，直到达到所需的总数 2_n_ + _p_。

 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n^2) | O(2^n * n^2) | O(n^2) | O(n^2) | 太慢了 |

 ## 算法演练

1. 初始化一个空的边列表。 我们将逐步构建图表。 
2. 用模算术构造一个简单的循环，将每个顶点连接到接下来的两个顶点。 对于顶点 i，添加边 (i, i+1) 和 (i, i+2)，并使用模 n 进行环绕。 这确保每个顶点最初的度数为 2，满足所有 k 的子图边界。 
3. 计算添加的边数。 此时，我们正好有 2_n_ 条边。 
4. 如果_p_ > 0，我们需要添加_p_条边。 从较小的 i 和 j > i 开始，迭代尚未连接的顶点对 (i, j)。 对于每个这样的对，添加边并递增计数，直到总数达到 2_n_ + _p_。 因为 n 很小并且子图界限很宽松，所以这总是可能的。 
5. 将边列表输出为顶点对，确保编号从 1 开始。 

工作原理：基本循环确保 k 个顶点的每个子集最多有 2_k_ 条边，因为在此阶段没有顶点超过 2 度。 在非相邻顶点之间添加 _p_ 额外边绝不会创建违反 2_k_ + _p_ 界限的子集，因为 _p_ 是全局考虑的。 该算法增量地构建图，同时保持子图不变。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, p = map(int, input().split())
        edges = []
        
        # Step 1: add base 2*n edges using modular neighbors
        for i in range(n):
            edges.append((i+1, (i+1) % n + 1))      # connect to next
            edges.append((i+1, (i+2) % n + 1))      # connect to next-next
        
        # Step 2: add extra p edges
        if p > 0:
            added = 0
            for i in range(n):
                for j in range(i+3, n):
                    if added >= p:
                        break
                    edges.append((i+1, j+1))
                    added += 1
                if added >= p:
                    break
        
        for a, b in edges:
            print(a, b)

solve()
```该解决方案首先构建可预测的基本模式，其中每个顶点都有两条到附近邻居的边。 模算术可以正确处理循环。 额外的 _p_ 边被添加到不是直接邻居的顶点，以避免违反子图边界。 仔细的索引可确保不会出现相差一的错误。
