 ## 解决方案
 ## 问题理解

 对于每个测试用例，我们都会得到一个起始编号`x`和一个整数`k`。 如果一个数字的十进制数字之和能被整除，则该数字被认为是美丽的`k`。 

任务是找到最小的整数`y`这样`y ≥ x`和的数字和`y`可以整除`k`。 

从算法的角度来看，这些限制令人惊讶地小。 的价值`x`可以达到`10^9`， 但`k`至多是`10`。 测试用例的数量可以大到`10^4`，因此单个测试用例的解决方案应该非常便宜。 

从约束中观察到的关键是数字和很小。 即使对于周围的数字`10^9`, 数字和最多为`9 × 10 = 90`。 自从`k ≤ 10`，我们不需要搜索很远就能找到有效的答案。 这使得直接搜索变得实用。 

一个容易犯的错误是假设答案必须严格大于`x`。 考虑：```
x = 777, k = 3
```数字和是`7 + 7 + 7 = 21`，它已经可以被整除`3`。 正确答案是：```
777
```另一个常见的错误是检查数字本身的整除性而不是其数字和。 例如：```
x = 17, k = 8
```数量`17`不能被整除`8`，但它的数字和是`1 + 7 = 8`，可除以`8`。 正确答案是：```
17
```当第一个有效数字出现之前几个连续的数字失败时，就会出现第三种微妙的情况。```
x = 1, k = 10
```数字和为：```
1 -> 1
2 -> 2
...
18 -> 9
19 -> 10
```答案是：```
19
```仅检查附近几个数字的粗心实现可能会错过第一个有效的候选者。 

## 方法

 最直接的方法就是从`x`并一一重复测试数字。 

对于候选人编号`cur`，计算其数字和。 如果该总和可以除以`k`，我们找到了最小的有效答案，因为我们按升序检查了数字。 否则，增加`cur`并继续。 

暴力破解是正确的，因为每个数字都大于或等于`x`按顺序检查，遇到的第一个漂亮数字一定是可能的最小答案。 

通常，对整数进行线性搜索是危险的。 如果有效答案之间的差距可能非常大，那么最坏情况下的运行时间将变得不可接受。 

关键的观察是`k ≤ 10`。 数字和经常变化，在任何相当小的数字范围内，我们都会遇到可以被以下任意值整除的数字和`1`到`10`。 实际上，搜索永远不会走得太远。 这正是问题的预期解决方案。 

计算数字和只需要几次运算，因为数字最多有十位数字。 即使与`10^4`测试用例，总工作量很小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力搜索 | O(g·d) | O(1) | O(1) | 已接受 |
 | 最优（相同观察）| O(g·d) | O(1) | O(1) | 已接受 |

 这里`g`是找到答案之前检查的候选者数量，并且`d`是位数。 自从`k ≤ 10`,`g`仍然很小。 

## 算法演练

 1. 阅读`x`和`k`。 
2. 设置`cur = x`。 
3. 计算数字之和`cur`。 
4. 如果数字和能被整除`k`， 输出`cur`并停止处理这个测试用例。 
5.否则增加`cur`一个。 
6. 重复步骤 3。 

搜索按递增的数字顺序进行。 遇到的第一个有效数字自动成为最小的有效答案。 

### 为什么它有效

 在每次迭代中，来自的所有整数`x`通过`cur - 1`已被检查并拒绝，因为它们的数字和不能被整除`k`。 

When the algorithm stops at some value`cur`，它的数字和可以被整除`k`。 因为每个较小的数字都大于或等于`x`已经检查并发现无效，不存在更小的有效答案。 因此`cur`正好是不小于的最小美丽数`x`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def digit_sum(n):
    s = 0
    while n:
        s += n % 10
        n //= 10
    return s

t = int(input())

for _ in range(t):
    x, k = map(int, input().split())

    cur = x
    while True:
        if digit_sum(cur) % k == 0:
            print(cur)
            break
        cur += 1
```辅助函数使用重复的模数和除法运算来计算数字和。 这避免了将数字转换为字符串，尽管这两种方法都足够快。 

对于每个测试用例，程序开始于`x`并一一核对候选人。 一旦数字和可被整除，循环就会终止`k`被发现。 

一个微妙的边界条件是当`x`本身就已经很美了。 该算法自然地处理这个问题，因为`cur`开始于`x`，因此第一个检查包括起始编号。 

不存在溢出问题，因为 Python 整数是无界的，并且按照竞争性编程标准，问题值已经非常小。

 | 测量| 复杂性 | 说明|

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    def digit_sum(n):
        s = 0
        while n:
            s += n % 10
            n //= 10
        return s

    t = int(input())
    ans = []

    for _ in range(t):
        x, k = map(int, input().split())
        cur = x

        while True:
            if digit_sum(cur) % k == 0:
                ans.append(str(cur))
                break
            cur += 1

    print("\n".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue()

 ## 边缘情况

 考虑：```
1
777 3
```该算法开始于`cur = 777`。 数字和是`21`， 和`21 % 3 = 0`。 循环立即停止并输出：```
777
```这证实了答案可能正是`x`。 

考虑：```
1
17 8
```数字和是`1 + 7 = 8`。 自从`8 % 8 = 0`，算法输出：```
17
```这表明该属性取决于数字之和，而不取决于数字本身的整除性。 

考虑：```
1
1 10
```该算法按顺序检查数字：```
1, 2, 3, ..., 18, 19
```第一个数字的总和可被整除`10`发生在`19`，其数字和为`10`。 输出是：```
19
```此案例说明了为什么即使许多连续数字都失败，搜索也必须继续，直到找到有效的数字和。
