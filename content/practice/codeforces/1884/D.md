 ## 解决方案
 ## 问题理解

 我们得到一个整数数组`a[1..n]`，每个都在 1 和 n 之间。 我们需要计算对的数量`(i, j)`和`i < j`这样就没有`k`为此，两者`a[i]`和`a[j]`可以被整除`a[k]`。 换句话说，如果数组中没有可除该对的两个元素的公约数，则该对是“好”的。 

输入可以有多个测试用例，并且总和`n`所有测试用例最多可达一百万。 这立即排除了任何明确检查所有对的解决方案`i < j`，因为这将是 O(n^2) 次操作，并且在最坏的情况下可能达到 10^12 次操作。 

一个关键的微妙之处是，即使`a[i]`和`a[j]`是互质的，如果存在一些，它们仍然可能是“坏的”`a[k]`在将两个数字相除的数组中。 例如，如果`a = [2, 4, 4]`， 然后`(2, 3)`不好，因为两者都可以被整除`2`（虽然`a[2] = 4`和`a[3] = 4`是相等的）。 

简单实现可能会失败的边缘情况包括所有元素都相等或某些元素为 1 的数组。例如，如果所有数字都是`1`，没有一对是好的，因为每个数字都可以被整除`1`。 同样，如果素数和合数是这些素数的倍数，则错误地计算整除性可能会产生错误的结果。 

## 方法

 蛮力方法将迭代所有对`(i, j)`并检查所有`k`无论`a[i] % a[k] == 0`和`a[j] % a[k] == 0`。 这是正确的，但在最坏的情况下需要 O(n^3) 次操作，这对于 n 高达 10^6 来说太慢了。 

关键的观察是一对`(i, j)`是坏的当且仅当存在一个数字`x`在除以两者​​的数组中`a[i]`和`a[j]`。 我们可以计算有多少个数字可以被每个数字整除，而不是检查数字对`x`在数组中。 让`cnt[x]`是能被整除的数字的个数`x`。 那么，由于以下原因而不好的对的数量`x`是`cnt[x] * (cnt[x] - 1) // 2`。 

我们可以计算`cnt[x]`有效地使用类似筛子的方法。 对于每个数字`v`在数组中，我们添加 1`cnt[d]`对于所有除数`d`的`v`。 这避免了显式检查所有对。 最后，坏对的总数是所有除数的总和，好对的数量是`total_pairs = n * (n - 1) // 2 - bad_pairs`。 

这将问题从成对检查转变为计数问题，使用除数累加技术，这在 O(n log n) 时间内是可行的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) | O(n^3) | O(1) | O(1) | 太慢了 |
 | 计算除数 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 对于每个测试用例，请阅读`n`和数组`a`。 
2.初始化频率数组`freq`大小的`n+1`计算每个数字出现的次数`a`。 
3. 对于每个数字`v`在`a`, 增量`freq[v]`。 
4. 初始化`cnt`大小数组`n+1`为零。 这将存储有多少个数字可以被每个索引整除。 
5. 对于每个数字`i`从 1 到 n，迭代倍数`j = i, 2*i, 3*i, ...`最多`n`并添加`freq[j]`到`cnt[i]`。 计算数组中有多少个数字可以被整除`i`。 
6. 对于每个`i`从 1 到 n，计算由以下因素贡献的坏对的数量`i`作为`cnt[i] * (cnt[i] - 1) // 2`并对它们求和。 
7. 计算总对数`total_pairs = n * (n - 1) // 2`。 
8. 好对的数量是`total_pairs - bad_pairs`。 
9. 输出每个测试用例的结果。 

**为什么有效：** 该算法正确计算所有共享公约数的对`i`无需重复计算，因为每个除数`i`只贡献可被它整除的对。 对所有除数求和就得到了坏对的总数。 从总对中减去只留下好的对。 像筛子一样的计数确保不会漏掉任何一对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        freq = [0] * (n + 2)
        for v in a:
            freq[v] += 1

        cnt = [0] * (n + 2)
        for i in range(1, n + 1):
            for j in range(i, n + 1, i):
                cnt[i] += freq[j]
        
        bad_pairs = sum(c * (c - 1) // 2 for c in cnt[1:n+1])
        total_pairs = n * (n - 1) // 2
        print(total_pairs - bad_pairs)

if __name__ == "__main__":
    solve()
```第一个循环构建一个数字频率表，以了解每个值出现的次数。 嵌套循环就像一个筛子：对于每个`i`，我们将所有可被整除的数字相加`i`到`cnt[i]`。 这`bad_pairs`使用整数除法仔细计算总和以避免浮点错误。 这完全避免了成对迭代。 我们只需要大小的数组`n+1`，考虑到限制，这是安全的。 

## 工作示例

 **示例1：**

 输入：`[2, 3, 4, 4]`,`n=4`| 我| 频率 | cnt[我] |
 | --- | --- | --- |
 | 1 | 数 1,1,2,2 | 4 |
 | 2 | 数 0,1,2,2 | 3 |
 | 3 | 计数 0,1,0,0 | 1 |
 | 4 | 计数 0,0,2,2 | 2 |

 坏对 = sum(cnt[i]_(cnt[i]-1)/2) = (4_3/2)+(3_2/2)+(1_0/2)+(2_1/2) = 6 + 3 + 0 +1 = 10

 总对 = 4_3/2 = 6

 好的对 = 6 - 10 = 3 （与样本输出匹配）。 

**示例2：**

 输入：`[6, 8, 9, 4, 6, 8, 9, 4, 9]`,`n=9`

`freq`计算每个数字，`cnt[i]`聚合整除计数。 求和后`cnt[i]*(cnt[i]-1)//2`我们发现`bad_pairs=16`，总对=36，good_pairs=20。 该算法规模很大`n`高效。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) | O(n log n) | 1..n 上的外循环和 i 的倍数上的内循环总和为 n * (1/1 + 1/2 + ... + 1/n) ≈ n log n |
 | 空间| O(n) | 数组`freq`和`cnt`大小为 n+1 |

 鉴于总和`n`在所有 ≤ 10^6 的测试用例中，该算法可以轻松地适应 2 秒和 256 MB 内存。
