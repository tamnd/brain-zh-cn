 **求解时间：** 1m 3s

 ## 解决方案
 ## 问题理解

 我们得到一个代表社交网络的无向图。 每个顶点都是一个轮廓，每个边都是一个友谊。 

两种不同的轮廓`i`和`j`如果其他所有个人资料都以完全相同的方式看待它们，则被视为双打。 对于每个顶点`k ≠ i, j`，或者两个边缘`(i, k)`和`(j, k)`存在，或者都不存在。 之间的友情状况`i`和`j`它们本身对于这个定义并不重要。 

用图的术语来说，如果我们忽略顶点本身，那么`i`和`j`必须具有相同的邻域。 唯一的微妙之处在于边缘的存在或不存在`(i, j)`应该不影响比较。 

我们必须计算有多少无序顶点对满足这个属性。 

限制条件非常大。 两个都`n`和`m`可以达到`10^6`。 具有一百万个顶点的图立即排除了任何成对比较邻接表的算法。 甚至存储一个`n × n`结构是不可能的。 由于时间限制为 3 秒，我们需要接近线性或`O(m log n)`。 

该图是稀疏的，因为`m ≤ 10^6`，而完整的图表`10^6`顶点将大致包含`5·10^11`边缘。 这表明基于邻接表的处理是正确的方向。 

一些边缘情况很容易被错误处理。 

考虑孤立的顶点：```
4 0
```每个顶点都有相同的邻域，即空集。 每对都是双精度数，所以答案是：```
6
```仅处理出现在边中的顶点的解决方案可能会完全忘记孤立的顶点。 

另一个微妙的情况是两个顶点仅因为它们彼此连接而不同。```
2 1
1 2
```答案是：```
1
```没有第三个顶点，因此条件为空真。 如果我们比较普通的邻接表，我们得到`{2}`相对`{1}`，这是不同的。 直接的邻域比较会错误地拒绝这一对。 

一个稍微大一点的例子显示了同样的现象：```
3 2
1 3
2 3
```顶点`1`和`2`是双精度数，因为两者都只连接到顶点`3`。 

现在添加边缘`(1,2)`：```
3 3
1 2
1 3
2 3
```顶点`1`和`2`仍然是双打。 它们的邻接表中唯一的区别是彼此不同。 任何在不考虑这一点的情况下比较完整社区的方法都会失败。 

核心难点是如何有效地处理“所有其他顶点”这个短语。 

## 方法

 最直接的解决方案是检查每对顶点`(i,j)`。 对于每一对，将它们与所有剩余顶点的关系进行比较。 如果每三个顶点看到`i`和`j`同样，数对。 

这是正确的，因为它遵循字面定义。 不幸的是有`O(n²)`成对，并且每次比较可能需要检查`O(n)`顶点。 最坏的情况是`O(n³)`，这对于`n = 10^6`。 

我们需要重新表述条件。 

认为`N(v)`表示顶点的邻居集合`v`。 

如果顶点`u`和`v`不相邻，那么定义简单地说：```
N(u) = N(v)
```因为两个邻域都不包含另一个顶点。 

如果顶点`u`和`v`相邻，则每个邻域都包含另一个顶点。 相互移除后，剩余的邻居必须匹配：```
N(u) \ {v} = N(v) \ {u}
```这一观察结果将问题转化为通过邻域签名对顶点进行分组。 

挑战在于邻接表可能包含多达一百万个顶点，因此直接比较集合的成本太高。 相反，我们为每个顶点分配一个哈希值，并通过其成员的哈希值之和来表示邻域。 

让`rnd[x]`是分配给顶点的随机 64 位数字`x`。 

对于每个顶点：```
H(v) = Σ rnd[x]   over all x in N(v)
```以压倒性的概率，相等的邻域集合产生相等的和，不同的集合产生不同的和。 

现在考虑这两种情况。 

对于不相邻的双打，我们需要相等的普通邻域。 我们可以简单地将顶点分组`H(v)`。 

对于相邻的双打，我们需要：```
N(u) \ {v} = N(v) \ {u}
```等效地：```
H(u) - rnd[v] = H(v) - rnd[u]
```定义：```
G(u,v) = H(u) + rnd[u]
```然后，相邻顶点恰好在以下情况下形成有效对：```
H(u) + rnd[u] = H(v) + rnd[v]
```这导致了一个非常有效的策略。 

首先计算所有具有相同的顶点对`H(v)`。 这些是不相邻的双打。 

然后计算所有具有相同的顶点对`H(v)+rnd[v]`。 这包括相邻对和不相邻对，因此我们无法将它们全部相加。 相反，我们只检查实际的边缘`(u,v)`并检查是否：```
H(u)+rnd[u] = H(v)+rnd[v]
```每条这样的边都会贡献一个额外的双对。 

该图只有`m ≤ 10^6`边缘，所以最后的检查很便宜。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 太慢了|
 | 最佳 | 预计 O(n + m) | O(n) | 已接受 |

 ## 算法演练

 1.为每个顶点分配一个随机的64位整数`rnd[i]`。 
2. 创建数组`H`初始化为零。 
3.对于每一个边缘`(u,v)`， 添加`rnd[v]`到`H[u]`并添加`rnd[u]`到`H[v]`。 

这一步之后，`H[v]`是顶点邻域的哈希值`v`。 
4. 将所有顶点分组`H[v]`。 

如果一个组包含`k`顶点，添加：```
k(k-1)/2
```到答案。 

这些是具有相同普通邻居的对。 
5. 对于每个顶点计算：```
T[v] = H[v] + rnd[v]
```6. 对于每一个边缘`(u,v)`，检查是否：```
T[u] = T[v]
```如果为真，请在答案中加一。 

这完全对应于：```
H(u)-rnd[v] = H(v)-rnd[u]
```这意味着邻域在相互移除后变得相同。 
7. 输出最终计数。 

### 为什么它有效

 对于不相邻的顶点，双重条件相当于它们的整个邻域集相等。 哈希值`H(v)`是由所有邻居构建的`v`，因此相等的邻域会产生相等的哈希值。 对相等的哈希值进行分组可以精确计算这些对。 

对于相邻顶点，每个邻域因另一个端点的存在而不同。 从两侧删除该端点给出了条件：```
N(u)\{v} = N(v)\{u}
```哈希表示将其转换为：```
H(u)-rnd[v] = H(v)-rnd[u]
```这在代数上等价于：```
H(u)+rnd[u] = H(v)+rnd[v]
```仅在现有边上检查此相等性才能准确计算相邻的双对。 

每对都属于这两个类别之一，并且没有一对被计算两次。 因此该算法是正确的。 

## Python 解决方案```python
import sys
import random
from collections import defaultdict

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    rnd = [0] * (n + 1)
    rng = random.Random(154154)

    for i in range(1, n + 1):
        rnd[i] = rng.getrandbits(64)

    h = [0] * (n + 1)
    edges = []

    for _ in range(m):
        u, v = map(int, input().split())
        edges.append((u, v))

        h[u] += rnd[v]
        h[v] += rnd[u]

    groups = defaultdict(int)

    for i in range(1, n + 1):
        groups[h[i]] += 1

    ans = 0

    for cnt in groups.values():
        ans += cnt * (cnt - 1) // 2

    t = [0] * (n + 1)
    for i in range(1, n + 1):
        t[i] = h[i] + rnd[i]

    for u, v in edges:
        if t[u] == t[v]:
            ans += 1

    print(ans)

solve()
```第一阶段为每个顶点分配一个随机 64 位值。 这些价值观充当社区建设的指纹。 

在读取边缘时，代码会更新两个端点的邻域哈希。 处理完所有边缘后，`h[v]`包含所有邻居的指纹之和`v`。
