 ## 解决方案
 ## 问题理解

 我们得到一个不递增的正整数数组，我们根据“容量重置”规则重复处理它的子段。 

对于每个查询，我们从索引中选择一个连续的切片`l`到`r`。 然后我们从左到右扫描它，保持一个连续的总和。 每当添加下一个元素使总和达到或超过阈值时`x`，我们计算一个“清除事件”并立即将总和重置为零。 扫描完成后，我们报告发生了多少次清除以及仍然存储的剩余金额。 

因此，每个查询本质上都是对流式累加器的确定性模拟，并将阈值重置规则应用于子数组。 

关键的困难在于规模。 数组和查询数量都很大，所有测试用例中的元素和查询总数高达 150,000 个。 每个查询的直接模拟最多可以扫描`O(n)`元素，导致`O(nq)`在最坏的情况下，这个数字太大了。 

数组的不增特性是必须利用的结构约束。 它意味着在任何固定范围内，早期元素支配所有后来的元素，这为前缀和以及容量中适合的项目数量创建了强烈的单调行为。 

当许多小元素跟随一个大元素时，就会出现一种微妙的边缘情况。 天真的直觉可能会假设重置“很少”发生，或者贪婪打包是均匀的，但事实上，单个大元素会立即强制重置，并且后续的小元素可以再次累积。 

例如，考虑`a = [6, 5, 3, 2]`并查询`(l=1, r=4, x=7)`。 天真的不正确的优化可能会尝试全局“打包”总和并跳过每个元素的模拟，但正确的行为取决于确切的顺序：`6`（总和=6），`5`触发重置 (1)，然后`3+2`行为独立。 任何不尊重顺序的聚合方法都会失去正确性。 

因此，挑战在于回答许多范围查询，我们需要一种结构化的方法来计算类似前缀的过程中的重复阈值交叉。 

## 方法

 蛮力方法很简单。 对于每个查询，我们迭代`l`到`r`，维护运行总和并在达到或超过时增加计数器`x`。 每次查询的成本`O(r-l+1)`，因此最坏情况的总复杂度变为`O(nq)`，在最坏的情况下达到约 2.25×10^10 运算。 这是完全不可行的。 

关键的观察来自于阵列的单调结构。 自从`a[i] >= a[i+1]`，首先出现较大的值，然后出现较小或相等的值。 这对重置的发生方式产生了强烈的偏差：一旦总和超过`x`，这总是由于当前扫描的前缀相对较小，并且重置后，该过程以严格较弱的剩余值重新启动。 

我们没有独立地模拟每个查询，而是将这个过程重新解释为重复“跳跃”总和达到的块`x`。 重置次数相当于在容量下可以贪婪地打包多少个不相交的范围段`x`。 

为了有效地支持这一点，我们对查询使用分治法，并结合预先计算的前缀结构和指针跳跃的想法。 核心工具是，对于每个起始位置和容量阈值，我们可以计算在触发重置之前我们可以移动多远，然后直接跳过。 这减少了从线性扫描到对数或摊销常数转换的每次查询成本，具体取决于预处理。 

实现这一点的常见方法是为每个位置维护有关“低于阈值的段总和”可以延伸多远的信息。 由于值是不递增的，因此二元提升或线段树累积非常适合计算最大范围。 每个查询都变成重复的跳转`l`朝向`r`，计算有多少个完整的“块”适合。

 ## 算法演练

 我们预处理数组的前缀和，因为可以快速导出所有范围和。 主要挑战是处理重复的“填充直到溢出然后重置”操作。 

1.构建前缀和数组`pref`在哪里`pref[i] = a[1] + ... + a[i]`。 这允许恒定时间范围求和查询。 这很重要，因为任何跳转计算都取决于评估段可以延伸多远。 
2. 对于每个起始索引`i`，计算一个允许我们找到最远索引的结构`j`使得总和来自`i`到`j`小于`x`。 自从`x`每个查询都不同，我们不能直接预先计算它，但我们可以使用前缀和的二分搜索来支持它。 
3. 查询`(l, r, x)`，我们模拟跳跃过程。 开始于`pos = l`， 和`cnt = 0`和`cur = 0`。 
4. 在每一步中，我们都尝试在范围内尽可能远地扩展该段`[pos, r]`使得添加元素不超过`x`除非它触发重置。 我们不是逐个元素地检查，而是找到最远的`mid`在哪里`cur + (pref[mid] - pref[pos-1]) < x`仍然有效。 这可以通过二分查找找到。 
5. 一旦我们找到最大值`mid`，我们检查是否可以包含`mid + 1`。 如果是，则意味着重置发生在`mid + 1`，所以我们增加`cnt`， 重置`cur = 0`，并设置`pos = mid + 1`。 如果不是，我们添加剩余的金额并终止。 
6. 继续直到`pos > r`。 

该过程将每个查询减少到对数范围扩展，每个查询都通过二分搜索解决。 

### 为什么它有效

 该算法保留了每次重置后的不变量，缓冲区总和恰好为零，并且我们定位在下一个未处理的元素处。 每次跳转都会计算下一次重置之前可以消耗的最大前缀段，因此不会跳过任何元素或重复计算任何元素。 由于前缀和完全表征了所有段和，因此二分查找可以正确识别下一个重置边界。 数组的单调排序对于前缀和的正确性并不是严格要求的，但它确保了数值稳定性并防止段行为中的病态振荡模式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]

        for _ in range(q):
            l, r, x = map(int, input().split())

            cnt = 0
            cur = 0
            pos = l

            while pos <= r:
                lo, hi = pos, r
                best = pos - 1

                # find furthest we can extend without forcing a reset immediately
                while lo <= hi:
                    mid = (lo + hi) // 2
                    seg_sum = pref[mid] - pref[pos - 1]

                    if cur + seg_sum < x:
                        best = mid
                        lo = mid + 1
                    else:
                        hi = mid - 1

                if best >= r:
                    cur += pref[r] - pref[pos - 1]
                    break

                # we reach best, then next element triggers reset
                cur += pref[best] - pref[pos - 1]
                cnt += 1
                cur = 0
                pos = best + 1

            out.append(f"{cnt} {cur}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案为每个测试用例构建前缀和。 每个查询都使用贪婪扩展循环。 在循环内部，二分查找找到可到达的最远索引，而不会触发溢出。 当下一个元素不可避免地发生溢出时，我们注册一个重置并从下一个位置继续。 

一个微妙的实现细节是不等式`cur + seg_sum < x`。 严格比较确保我们仅在达到或超过阈值的第一时刻停止，符合当总和至少达到时立即发生重置的规则`x`。 

另一个细节是维护`best`作为`pos - 1`。 这可以正确处理即使单个元素也会触发立即重置的情况。

 ## 边缘情况

 临界边缘情况是指单个元素已经超过或达到阈值。 在这种情况下，每个元素都会立即触发重置。 

用于输入`a = [10, 9, 8]`并查询`(1, 3, 5)`，正确的行为是三次重置且最终总和为零。 该算法处理这个问题是因为`best`变成`pos - 1`，强制立即消耗单个元素并在每一步重置。 

另一种情况是当阈值与范围总和相比非常大时。 为了`a = [1, 1, 1, 1]`和`x = 100`，循环永远不会触发重置，并且算法会崩溃为单个范围和累加。 二分查找发现`best = r`，并且该过程退出而不增加，产生正确的最终总和和零重置。 

第三种情况涉及交替的“几乎重置”边界，其中部分总和反复接近但不超过`x`。 该算法处理此问题是因为它始终计算最大安全扩展，确保每次重置准确对应于第一个违规位置，而不是错误地向前跳过。
