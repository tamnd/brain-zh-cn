 ## 解决方案
 ## 问题理解

 我们处理一系列的转弯。 当前分数从 0 开始。 

轮到时`i`，我们有两种可能的变换：

 如果我们吃到红牌，新的比分就变成`k -> k - a[i]`如果我们拿了蓝卡，新的分数就变成`k -> b[i] - k`我们必须在每个回合中准确选择一个转换。 毕竟`n`反过来，我们想要能够达到的最大最终分数。 

最直接的解释是，每一轮都对当前分数应用两个仿射变换之一。 困难在于现在所做的选择会改变未来所有回合所看到的分数。 

重要的约束是总的`n`所有测试用例最多`10^5`。 任何探索所有可能的决策序列的算法都是不可能的，因为有`2^n`选择卡片的不同方式。 甚至`O(n^2)`当线性解可行时，这里就没有必要了。 我们应该期待动态规划或贪婪观察会极大地压缩状态。 

问题的一个微妙方面是分数可能会变成负数，并且两者`a[i]`和`b[i]`也可能是负数。 任何假设分数总是增加的推理都会失败。 

考虑：```
n = 1
a = [5]
b = [-10]
```两个可能的最终分数是`-5`和`-10`，所以答案是`-5`。 

另一个容易犯的错误是假设每回合后只保留最大分数就足够了。 

例子：```
Current possible scores: {100, -100}

Next turn:
a = 0
b = 0
```从`100`我们可以得到`{100, -100}`。 

从`-100`我们可以得到`{-100, 100}`。 

未来的最大结果可能来自任一极端。 中间值不足以描述状态。 

第三个陷阱是具有固定宽度整数的语言中的整数溢出。 分数最多可以累积变化`10^5`轮次，每个轮次涉及的值高达`10^9`。 答案很容易超出 32 位范围。 Python 会自动处理这个问题，但 C++ 解决方案必须使用`long long`。 

## 方法

 暴力解决方案每次都会尝试两种卡选择。 

从分数开始`0`，每回合可达到的分数数量加倍。 后`n`轮数最多可达`2^n`州。 暴力破解是正确的，因为它明确地检查了每个可能的游戏序列，但是对于`n = 100000`它大得令人绝望。 

为了找到更好的方法，我们需要了解回合如何转换一组可能的分数。 

假设在一轮之前可达到的分数集是`S`。 

对于任何分数`x`在`S`，这两个转移是：```
x - a[i]
b[i] - x
```两者都是线性函数`x`。 

我们只对所有回合后可达到的最高分数感兴趣。 这建议跟踪可达集合的一些摘要而不是整个集合。 

关键的观察是，如果回合前可获得的分数形成一个区间`[mn, mx]`，然后对该区间中的每个值应用任一变换会产生另一个区间。 

对于红色操作：```
x -> x - a[i]
```的形象`[mn, mx]`是```
[mn - a[i], mx - a[i]]
```对于蓝色操作：```
x -> b[i] - x
```图像是```
[b[i] - mx, b[i] - mn]
```这两个区间的并集又是一个区间。 要了解原因，请注意：```
(mx - a[i]) - (b[i] - mx)
= 2*mx - (a[i] + b[i])

(b[i] - mn) - (mn - a[i])
= (a[i] + b[i]) - 2*mn
```自从`mn <= mx`，这些量中至少有一个是非负的。 因此，两个音程总是重叠或接触，因此它们的并集是一个连续音程。 

最初可达集是`{0}`，这是一个区间。 通过归纳，每次转弯后，可达集仍然是一个区间。 

一旦我们知道了这一点，我们只需要它的最小值和最大值。 

设当前区间为`[mn, mx]`。 

下一个区间有端点：```
new_mn = min(mn - a[i], b[i] - mx)
new_mx = max(mx - a[i], b[i] - mn)
```我们处理所有转弯并输出最终的最大端点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(2^n) | O(2^n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化两者`mn`和`mx`到`0`，因为在任何回合之前唯一可获得的分数是`0`。 
2. 流程从左向右转动。 
3. 对于当前回合，计算应用任一操作后可达到的最小值：```
new_mn = min(mn - a[i], b[i] - mx)
```红色区间的最小值是其左端点`mn - a[i]`。 蓝色区间的最小值是其左端点`b[i] - mx`。 
4. 计算应用任一操作后可达到的最大值：```
new_mx = max(mx - a[i], b[i] - mn)
```红色区间的最大值是`mx - a[i]`。 蓝色区间的最大值是`b[i] - mn`。 
5. 更换`(mn, mx)`和`(new_mn, new_mx)`。 
6.全部转完后，输出`mx`。 

### 为什么它有效

 不变量是在处理任意回合前缀后，每个可达分数都位于区间内`[mn, mx]`，并且该区间内的每个值都是可达的。 

基本情况是直接的，因为初始可达集是`{0}`。 

假设在转弯之前不变量成立。 对整个区间应用红色运算会产生一个区间，而应用蓝色运算会产生另一个区间。 这两个区间总是重叠的，因此它们的并集本身就是一个区间。 该并集中的最小值和最大值正是用于的公式`new_mn`和`new_mx`。 

因此，每次转动后，不变量仍然为真。 在最后，`[mn, mx]`正是所有可达到的最终分数的集合，因此答案是其最大终点`mx`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        mn = mx = 0
        
        for i in range(n):
            new_mn = min(mn - a[i], b[i] - mx)
            new_mx = max(mx - a[i], b[i] - mn)
            mn, mx = new_mn, new_mx
        
        print(mx)

solve()
```实现直接遵循区间 DP。`mn`和`mx`表示处理后的前缀后的最小和最大可达分数。 对于每一轮，我们计算两个变换间隔的极端端点并更新当前间隔。 

一个常见的实施错误是更新`mn`计算前`new_mx`。 两个公式都必须使用前一个区间，因此需要临时变量。 

另一个细节是自始至终都使用整数运算。 所有转换都是加法和减法，因此不会出现精度问题。
