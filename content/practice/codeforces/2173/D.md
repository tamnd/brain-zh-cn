 ## 解决方案
 ## 问题理解

 Taiga 被赋予一个正整数`n`并且可以准确地执行`k`移动。 在每一步中，她选择二的幂，`2^ℓ`，并将其添加到`n`。 每一步的分数是加法过程中发生的二进制进位的数量。 Taiga 希望最大化所有的进位总数`k`移动。 

例如，如果`n = 7`（`111`二进制），她补充道`2^0 = 1`，添加`111 + 001`结果`1000`并产生三个进位。 如果`k = 1`，总分为 3。如果`k > 1`，连续移动中 2 的幂的选择会影响未来发生的进位数量，因为进位可以通过已经有 1 的位传播。 

输入给出了多个测试用例。 每个测试用例都有`n`高达近`2^30`和`k`最多`10^9`。 有了这么大的`k`，迭代每一个动作或尝试每一个选择`ℓ`是不可行的。 我们需要一种策略，其工作时间大致与比特数成正比`n`， 不是`k`。 

当出现微妙的边缘情况时`n`其二进制形式有许多尾随 1。 添加`2^0`重复产生多个通过这些 1 传播的进位。 例如，`n = 3`（`11`二进制）和`k = 2`：添加`2^0`首先产生`11 + 01 = 100`，两个进位。 下一步必须考虑新的二元状态`100`。 不跟踪接下来要添加哪一位的幼稚方法会低估总进位。 

## 方法

 蛮力方法会尝试所有可能的动作。 在每一次行动中，我们都会检查每一个`ℓ`从 0 到最高设置位`n`并计算进位数。 这是正确的，因为它探索了所有选项，但是当`k`很大。 操作次数将是 O(k * 位数)，这对于`k = 10^9`。 

关键的见解是进位数量仅取决于连续的尾随 1`n`。 添加`2^0`到一个数字`m`尾随 1 生成`m + 1`携带。 为了最大化分数，我们总是想添加到最小的位`ℓ`这样`n`在该位置或更低位置有一个 1，因为这会产生最长的进位链。 一旦我们执行了这样的加法，尾随的就会变成一个 0，后面跟着零或下一个 1，然后重复该过程。 

实际上，问题简化为重复查找`n`，将其添加到分数中，然后递增`n`乘以 2 的相应幂。 这种方法仅取决于二进制长度`n`，所以它可以处理大`k`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(k * log n) | O(k * log n) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(log n + min(k, 尾随迭代次数)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，初始化`total_score`为零。 
2. 虽然`k > 0`, 确定当前连续尾随的个数`n`。 这可以使用以下方法完成`n & -n`或从最低有效位开始计数位。 
3.让`m`是尾随的数量。 相加的分数`2^0`在这种状态下是`m + 1`。 
4. 增量`total_score`经过`m + 1`。 
5. 更新`n`通过添加`2^0 << m`（相当于，`n += 2^0`，但在传播进位后，这会翻转尾随的进位）。 
6. 减量`k`1.
 7. 重复直到所有`k`使用动作。 
8. 输出`total_score`对于这个测试用例。 

为什么有效：最低可用位的每次加法都会在该步骤产生最大可能的进位。 尾随的决定了进位链，因此按顺序处理它们可以保证每次移动都是最佳的。 由于每次移动都严格减少或重置尾随移动，因此该过程收敛并最多使用`log n`迭代即使`k`很大。 如果`k`处理完所有尾数后剩下的，剩余的每一步加 1 进位，可以直接相加。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def max_carries(n, k):
    total = 0
    while k > 0:
        if n == 0:
            total += k
            break
        # count trailing ones
        trailing_ones = 0
        temp = n
        while temp & 1:
            trailing_ones += 1
            temp >>= 1
        total += trailing_ones + 1
        n += 1 << trailing_ones
        k -= 1
    return total

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    print(max_carries(n, k))
```解决方案如下`t`测试用例。 对于每个动作，它都会循环。 关键操作是计算尾随数，它决定了相加产生的进位数`2^0`。 更新后`n`并递减`k`，循环继续。 如果`n`达到零（所有位都被清除），剩余的移动每次贡献一个进位。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(log n + min(k, log n)) | O(log n + min(k, log n)) | 每次迭代最多使用 log n 位对尾随进行计数； k 次迭代的上限为 log n |
 | 空间| O(1) | O(1) | 仅存储了几个变量|

 该方法很容易处理`k`最多 10^9，因为一旦尾随的移动被耗尽，剩余的移动都是线性加法，每个移动贡献 1 个进位。

 ## 边缘情况

 如果`n = 0`和`k > 0`，每一步加 1 进位。 该算法立即检测到`n == 0`并添加`k`到总分，返回而不进行不必要的计算。 

如果`n`有一系列尾随 1，例如`n = 7`（`111`） 和`k = 1`，第一步添加`2^0`并产生三个进位。 循环正确计算尾随数并更新`n`到`1000`以二进制形式。 

为了`k`如果大于耗尽尾随所需的分数，则剩余的每一步都会在总分中加 1。 例如，`n = 1`,`k = 5`，第一个移动添加 2 个进位，然后接下来的四个移动每个添加 1，总共 6 个。算法自然地捕获了这种行为。
