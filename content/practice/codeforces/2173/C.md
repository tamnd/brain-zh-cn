 ## 解决方案
 ## 问题理解

 我们得到了一组数字，所有数字都在从 1 到大极限 k 的范围内。 从这个数组中，我们必须构造一组不同的整数 B，也在 1 和 k 之间，但要受到两个以非平凡方式相互作用的同时约束。 

第一个约束将 B 与输入数组联系起来：数组中的每个值都必须被 B “覆盖”，即对于每个数组元素 a_i，B 中至少有一个数字可以除它。 所以每个 a_i 都被分配给我们选择的某个除数。 

第二个约束则相反：B 中每个选定的数字 b 都必须得到数组的“支持”。 如果我们查看 b 到 k 的所有倍数，则这些倍数中的每一个都必须在输入数组中至少出现一次。 换句话说，仅当输入数组足够密集以包含其所有倍数时才允许使用 b。 

因此，B 同时是可整除数组的覆盖集，也是其整个多重闭包存在于数组内部的经过有效性过滤的数字子集。 

目标是使 B 尽可能小，或者报告不存在这样的集合。 

这些约束极大地影响了解决方案。 测试用例中的数组元素总数最多为 2·10^5，因此任何在 n 中大致线性或接近线性的解决方案都是可接受的。 然而，k 可以大到 10^9，这排除了在整个范围内迭代直至 k 的任何方法。 任何有效的解决方案都必须仅对实际出现在数组中的值进行操作，并且依赖于除数关系而不是枚举。 

一个关键的微妙之处在于 B 是一个集合，而不是多重集，并且其有效性取决于倍数的全局频率条件，而不仅仅是单个元素的局部整除性。 这使得天真的贪婪选择充满风险。 

一些边缘案例说明了典型的故障模式。 如果数组包含单个值（例如 2）并且 k 很大，人们可能会认为 B={2} 有效，但它会失败，因为像 4、6、8 到 k 的倍数可能不会全部出现。 相反，如果数组像从 1 到 k 的所有数字一样非常密集，则 B={1} 有效，因为 1 可以整除所有内容，并且所有倍数条件都得到满足。 

当数字以结构化方式丢失时，就会发生另一种失败情况。 例如，如果 a 仅包含素数，则 B 中的复合 b 不能有效，因为它需要不存在的倍数。 尝试为每个元素贪婪地选择除数的简单解决方案将无法检查此全局乘法约束。 

## 方法

 暴力方法会尝试考虑数组中出现的不同值的每个候选子集 B，然后验证这两个约束。 对于每个候选 B，我们将通过扫描所有 a_i 并测试整除性来检查覆盖范围，并通过扫描每个 b 的倍数（最多 k）并验证数组中的存在来检查有效性。 即使我们将 B 限制为 a 中的不同值，子集的数量在 n 中也是指数级的，并且由于多次检查，每个验证步骤至少涉及线性或更差的工作。 一旦 n 增长超过小限度，这很快就变得不可行。 

关键的见解是颠倒条件二的视角。 我们没有将 B 视为我们自由选择的东西，而是观察到条件二具有极大的限制性：仅当 b 的每个倍数（最多为 k）出现在数组中时，值 b 才符合条件。 这立即意味着这样的 b 必须“完全适合”数组的结构，特别是，b 的所有倍数必须已经存在于输入值中。

一旦我们确定了所有有效候选者，条件一就成为数组值的覆盖问题：每个 a_i 必须至少能被一个选定的 b 整除。 这自然可以通过贪婪地挑选未覆盖元素的代表来解决，但最重要的是，我们只从有效的候选人中挑选。 

第二个重要的观察结果是，如果值 x 有效，则 x 的任何倍数都不会自动有效，并且实际上通常无效，除非数组非常密集。 这意味着有效元素是稀疏的，并且可以使用不同值的频率计数来有效地进行预过滤。 

我们计算数组的频率图，然后，对于每个不同的值 x，我们验证 x 的所有倍数（直到最大当前值）是否都包含在数组中。 因为我们只迭代现有值的倍数，所以总的复杂性是可控的。 

一旦我们有了有效的集合，我们就需要确保覆盖范围。 对于每个尚未覆盖的 a_i，我们从有效集合中选择一个除数。 最佳策略是将每个未覆盖的值分配给其最小有效除数（或任何有效除数），确保我们不会过度选择。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 最佳 | O(n √A log A)（与除数有效线性）| O(n) | 已接受 |

 ## 算法演练

 1. 构建数组中所有值的频数表。 这允许 O(1) 检查数字是否存在。 
2. 从数组中提取不同值的集合，因为只有这些值才可能成为 B 的元素。 
3. 对于每个不同的值 x，通过验证频率表中是否存在 ≤ k 的所有倍数 x、2x、3x、... 来检查 x 是否“有效”。 如果缺少任何倍数，则 x 被拒绝。 此步骤确保我们保留的任何候选人都满足问题的第二个条件。 
4. 将所有有效值收集到候选列表中。 这些是我们唯一可以在 B 中放置的数字。 
5. 如果根本没有有效的候选者，则答案是不可能的，因为每个 a_i 必须被至少一个除数覆盖，并且不能安全地选择除数。 
6. 通过扫描数组贪婪地构建 B。 维护一个布尔数组或集合来指示哪些值已被覆盖。 
7. 对于每个a_i，如果已经被覆盖，则跳过。 否则，尝试 a_i 的所有约数并选择候选中的任何约数。 将其添加到 B 并将所选除数的所有倍数标记为已覆盖。 
8. 输出 B。 

核心思想是，有效性是根据候选者全局确定的，而覆盖范围是根据未覆盖的元素在本地处理的。 该算法之所以有效，是因为一旦为某个 a_i 选择了有效的除数，它就可以安全地表示整个除数类，而不会违反多重完整性约束。 

### 为什么它有效

 正确性取决于两个耦合的不变量。 首先，添加到 B 的每个元素都满足全局多重条件，因此它永远不会违反第二条规则。 其次，每次我们向 B 添加一个元素时，我们都会专门选择它，因为它会划分一个未覆盖的数组元素，从而保证覆盖所有 a_i 的进展。 由于每次插入都会严格增加覆盖元素的集合，并且 B 仅在必要时增长，因此我们不能以冗余或无效的构造而告终。 任何剩余的未覆盖元素必须在候选元素中至少有一个有效除数； 否则就会与可行性相矛盾。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def get_divisors(x):
    d = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            d.append(i)
            if i * i != x:
                d.append(x // i)
        i += 1
    return d

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    freq = {}
    for x in a:
        freq[x] = freq.get(x, 0) + 1

    vals = sorted(freq.keys())

    valid = set()

    for x in vals:
        ok = True
        m = x
        while m <= k:
            if m not in freq:
                ok = False
                break
            m += x
        if ok:
            valid.add(x)

    covered = set()
    B = []

    for x in a:
        if x in covered:
            continue

        found = False
        for d in get_divisors(x):
            if d in valid:
                B.append(d)
                found = True
                break

        if not found:
            print(-1)
            return

        # mark coverage
        b = B[-1]
        for m in range(b, k + 1, b):
            covered.add(m)

    print(len(B))
    print(*B)

if __name__ == "__main__":
    solve()
```频率图允许在验证倍数时进行恒定时间的成员资格检查。 有效性循环以 x 为步长，确保我们只触及相关倍数，而不是扫描整个范围。 

每个未覆盖元素的除数枚举是安全的，因为任何有效的解决方案都必须选择该元素的至少一个除数，因此我们保证找到一个候选者（如果存在）。 

覆盖范围更新有意扩大：一旦我们选择 b，b 的每个倍数都被视为覆盖范围，因为这些正是与执行未来选择相关的元素。

 ## 边缘情况

 一种重要的边缘情况是 k 很大但数组只包含很小的数字。 例如，如果 a = [2] 且 k = 100，则算法通过验证 100 以内的所有倍数是否存在来检查 2 的有效性。由于它们缺失，因此 2 被拒绝，并且算法正确返回 -1，因为没有有效的 b 可以满足第二个条件。 

另一种情况是密集结构数组，如 a = [1,2,3,4,5,6]。 这里每个数字都是有效的，因为直到 k 的所有倍数都出现在数组中。 该算法仍然只会选择一个小子集，因为一旦选择 1，它就已经涵盖了所有内容，从而防止了冗余添加。 

当一个元素可能有多个除数时，就会出现最后一种微妙的情况。 例如，a_i = 12 可能允许除数 2、3、4、6。只有其中一些是有效的，并且算法必须确保它不会意外选择无效除数。 除数扫描通过在选择之前将除数与预先计算的有效集相交来强制执行此操作。
