 ## 解决方案
 ## 问题理解

 每个机构在固定的天数内都会接待一定数量的访问。 根据这段历史，我们计算出一个频率数组$c_i$，其中每个值代表建立次数$i$被访问过。 

关键的观察结果是，最终答案仅取决于所有机构中的最大频率。 让$M = \max(c_i)$。 我们不使用原始计数，而是将问题转化为平衡任务：对于每个机构，我们定义赤字$h_i = M - c_i$，它告诉我们需要多少额外的访问才能“赶上”访问量最大的访问。 

然后，该过程会反复模拟减少这些赤字。 在每一步中，我们要么将两个赤字较大的机构配对并减少两者，要么在某些情况下，我们被迫统一增加所有赤字并同时增加目标最大值$M$。 当所有赤字变为零时，该过程终止。 

输出实际上是这些规则下所需的最小操作数，其中操作要么将两个赤字配对，要么在配对不可能或不足时全局增加所有赤字。 

这些限制意味着简单的模拟必须处理最多$O(D \cdot n)$相互作用，并且每次相互作用都涉及重复选择极值。 这表明任何依赖于重复扫描数组的解决方案都将太慢，甚至基于堆的模拟也必须仔细分析最坏情况的行为。 

当赤字总和为奇数或最大赤字与其他赤字相比太大时，就会出现微妙的失败情况。 

例如，如果我们有一个赤字为 2 的机构，比如$h = [2]$，该过程无法将其与任何东西配对。 天真的贪婪配对会立即失败，但正确的行为是触发全局增量，直到配对成为可能。 

另一个例子是$h = [3, 1]$。 总数是偶数，但最大的赤字超过了其他的。 除非算法明确检查可行性条件，否则贪婪配对无法适当减少不平衡。 

这些情况表明，正确性不仅取决于局部贪婪配对，还取决于全局结构可行性。 

## 方法

 蛮力视图直接模拟所描述的过程。 我们维护赤字的多重集并重复提取两个最大值。 如果两者都是正数，我们将它们递减，否则我们对所有元素应用全局增量并增加$M$。 这与问题陈述完全匹配，并且显然是正确的，因为它遵循相同的转换。 

然而，每个操作都需要提取最大值并且可能需要重新插入值。 高达$n$机构和潜在的$O(D)$增长于$M$，操作次数可以达到$O(D \cdot n)$。 即使有堆，每一步也会花费$O(\log n)$，使得总计$O(D \cdot n \log n)$，对于大输入来说是临界值或太慢。 

关键的见解是堆模拟只是模仿一个简单的可行性条件。 我们不需要显式地配对元素，我们只需要知道当前状态是否可以配对。 如果满足两个条件，则配对是可能的：剩余赤字总额是偶数，并且没有一个赤字太大而无法与其余赤字匹配。 如果任一条件失败，我们必须执行全局增量步骤。 

这将过程从重复提取转变为重复检查两个总量：赤字之和和最大赤字。 每个全局增量都会统一增加最大赤字和所有赤字，从而保留结构并允许我们跳过许多中间堆操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（堆模拟）| O(D·n log n) | O(D·n log n) | O(n) | 太慢了|
 | 优化贪婪可行性检查 | O(D) | O(n) | 已接受 |

 ## 算法演练

 我们与赤字阵列合作$h$，每个设施距离当前最大值有多远的多集表示$M$。 

1. 计算初始频率$c_i$， 放$M = \max(c_i)$，并定义$h_i = M - c_i$。 这使问题正常化，以便所有工作都按照赤字而不是原始计数进行。 
2. 维护两个聚合：总和$S = \sum h_i$和最大值$maxH = \max(h_i)$。 这些总结了在结构上是否可以在不模拟单独操作的情况下进行配对。 
3. 虽然至少存在一个非零$h_i$，检查系统是否处于“可配对”状态。 可配对性要求$S$是偶数并且$maxH \le S - maxH$。 第一个条件确保所有赤字都可以成对匹配，第二个条件确保最大的赤字不会主导其余的赤字。 
4. 如果配对条件失败，我们执行全局增量：增加每个$h_i$加 1 并增加$M$1. 此步骤相当于强制进行额外一轮，其中每个机构都变得相对更“需要”，从而恢复平衡。 
5. 当条件成立时，我们在概念上执行配对操作。 每次配对都会减少总和$S$2 并减少两个大值，但由于我们只跟踪聚合，所以我们更新$S$相应地并调整$maxH$如果需要的话。 
6. 继续，直到所有赤字为零。 

核心思想是我们从不显式地模拟单个对的删除； 我们只维护足够的全局结构来决定配对何时可行。 

### 为什么它有效

 系统的状态完全由多组赤字来表征，但对于操作的可行性来说，只有两个属性很重要：不匹配单元的总数是否为偶数，以及最大的赤字是否可以与剩余质量相匹配。 如果其中任何一个失败，则任何配对操作序列都无法完成当前配置，从而强制进行全局增量。 

每个全局增量都保留相对顺序，同时增加总容量，确保系统最终达到贪婪配对始终可能的状态。 由于配对总是在可行时以最佳方式减少系统，因此没有替代序列可以产生更少的全局增量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = list(map(int, input().split()))

    M = max(c)
    h = [M - x for x in c]

    S = sum(h)

    while True:
        if S == 0:
            break

        maxH = max(h)

        if S % 2 == 0 and maxH <= S - maxH:
            # pair greedily in aggregate
            # we only need to reduce sum to zero
            # each conceptual operation removes 2 units
            # but we don't simulate individually here
            # collapse directly
            break

        # global increment
        n = len(h)
        h = [x + 1 for x in h]
        S += n

    print(S // 2)

if __name__ == "__main__":
    solve()
```该代码将流程压缩为重复的可行性检查。 关键状态是赤字数组，但我们不是模拟每个配对，而是只跟踪配对在结构上是否可能。 一旦可行性成立，剩下的工作就是纯粹的配对，这有助于$S/2$操作，因为每次操作将总赤字减少 2。 

微妙之处在于，一旦满足可行性条件，就不再需要进一步的全局增量。 这就是为什么循环可以在那一刻立即终止。 

## 工作示例

 ### 示例 1

 考虑$c = [3, 1, 1]$。 然后$M = 3$， 所以$h = [0, 2, 2]$。 

我们跟踪这个过程：

 | 步骤| h状态| S | 最大高度| 状况 | 行动|
 | --- | --- | --- | --- | --- | --- |
 | 1 | [0,2,2]| 4 | 2 | 4 个偶数，2 ≤ 2 | 可配对|

 此时配对是可能的，因此我们停止全局增量并计算最终答案：$S/2 = 2$。 

这显示了一个干净的情况，系统已经足够平衡，可以避免任何全局调整。 

### 示例 2

 考虑$c = [5, 1, 1]$。 然后$M = 5$， 所以$h = [0, 4, 4]$。 

| 步骤| h状态| S | 最大高度| 状况 | 行动|
 | --- | --- | --- | --- | --- | --- |
 | 1 | [0,4,4]| 8 | 4 | 8 个偶数，4 ≤ 4 | 可配对|

 再次可以直接解决，但是如果我们有$c = [5, 1, 0]$，我们得到$h = [5, 0, 1]$，其中不平衡迫使配对生效之前至少有一个全局增量。 

这些例子表明，可行性是由全局结构而不是局部贪婪配对决定的。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + k) | 每个全局增量都会涉及所有元素，但总增量受达到可行性的速度限制 |
 | 空间| O(n) | 我们只存储赤字数组 |

 该算法保持高效，因为每个全局增量都有意义地增加了系统的容量，并且一旦配对变得可行，它就会立即以聚合数量的线性工作完成。

 ## 边缘情况

 对于像这样的单一机构$c = [k]$，归一化后赤字始终为零，因此算法立即返回零操作，因为不需要配对。 

对于高度倾斜的情况，例如$c = [100, 0, 0, 0]$，初始赤字由一种元素主导。 该算法在配对成为可能之前至少触发一个全局增量，这反映了在任何配对发生之前必须重新分配孤立质量的事实。 

对于统一的情况，例如$c = [2,2,2,2]$，所有赤字最初为零，因此系统立即终止而不进入循环。
