 ## 解决方案
 ## 问题理解

 我们在数轴上得到一个固定的大区间，以及几个较小的区间。 每个小区间都会覆盖大区间的某些部分。 任务不仅仅是了解大区间的覆盖范围，还要了解覆盖范围是如何按重叠深度分布的。 

对于每个整数阈值$h$，我们想知道被少于覆盖的大区间的总长度$h$小间隔。 同样，如果一个点被 0, 1, 2, … 间隔覆盖，我们想要累积覆盖计数最多为的所有部分$h-1$。 

直接的解释是计算大区间中的每个点有多少个小区间覆盖它，然后按覆盖值聚合长度。 这立即表明了减少：我们不是回答“覆盖范围 < h”，而是首先计算精确覆盖的长度$k$所有人的间隔$k$，然后在这些值上构建前缀和。 

大区间限制了所有贡献，因此小区间之外的任何部分都是无关紧要的。 这意味着每个段都可以安全地剪辑到范围内$[S, F]$。 

约束（由 ICPC 风格的语句结构隐含）通常允许最多$n$按顺序$2 \cdot 10^5$或更高。 因此，解决方案必须接近于$O(n \log n)$或者$O(n)$。 任何显式跟踪每个点的覆盖范围或使用每个查询扫描间隔的方法都会太慢。 

当段延伸到大间隔之外时，会出现微妙的故障情况。 例如，如果$[S, F] = [10, 20]$一个段是$[1, 15]$，仅部分$[10, 15]$很重要。 忘记剪辑会导致在感兴趣的域之外过度计算长度。 同样，段完全在外部$[S, F]$， 例如$[1, 5]$或者$[25, 30]$，必须完全忽略。 

当多个线段端点重合时，会出现另一种边缘情况。 事件的顺序变得至关重要。 如果一个段恰好在另一个段开始的地方结束，则错误的排序可能会人为地增加单个点上的重叠计数。 

## 方法

 一种简单的方法是将大间隔离散化为单位位置或细粒度坐标，并为每个点计算有多少个间隔覆盖它。 这在概念上是有效的：对于每个整数或坐标切片，我们检查所有段并在该段覆盖它时增加一个计数器。 在计算所有位置的覆盖计数后，我们可以按频率累积长度。 

这种做法是正确的，但是太慢了。 如果大区间长度为$L$，每点检查成本$O(nL)$，它退化成类似的东西$10^{10}$操作时两者$n$和$L$很大。 如果数轴很密集或端点很大，但连续的贡献很重要，即使坐标压缩也无济于事。 

关键的观察结果是覆盖范围仅在段端点发生变化。 在两个连续端点之间，活动段的数量保持不变，因此可以一次性计算出整个间隔的贡献。 这将问题转变为在扫描所有关键点的同时维护活动间隔的动态计数。 

我们将每个片段转换为两个事件，一个是它开始贡献时的事件，另一个是它停止时的事件。 剪辑后到$[S, F]$，每个段在其左边界贡献一个“打开”事件，在其右边界贡献一个“关闭”事件。 按排序顺序扫描这些事件使我们能够跟踪当前有多少段处于活动状态，并累积具有相同重叠计数的间隔长度。 

微妙但重要的细节是事件排序。 在同一坐标处，必须在打开事件之前处理关闭事件。 否则，恰好位于共享边界的点将被错误地视为同时被两个线段覆盖。 

这种扫描线方法将问题简化为对事件进行排序并执行线性扫描，这是高效且稳定的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n \cdot (F-S))$|$O(1)$或者$O(F-S)$| 太慢了|
 | 最佳扫描线 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将问题转化为计算，针对每个可能的覆盖计数$k$，恰好覆盖的大区间的总长度$k$段。 一旦知道这些值，阈值的答案$h$只是所有计数的总和$0$到$h-1$。 

1. 对于每个段$[b_i, e_i]$，首先将其替换为有意义的范围$[\max(b_i, S), \min(e_i, F)]$。 如果结果区间为空，则它没有任何贡献。 此步骤确保我们只处理段的相关部分。 
2. 对于每个剪辑片段，创建两个事件：一个在其开始处标记活动覆盖范围的增加，一个在其结束处标记活动覆盖范围的减少。 这些事件代表重叠计数发生变化的点。 
3. 将所有事件按坐标排序，当两个事件具有相同坐标时，先处理关闭事件，再处理打开事件。 这种排序可确保恰好位于边界的点不会在重叠线段中被重复计算。 
4. 维护一个变量`active`表示当前有多少段覆盖扫描位置，以及一个变量`last`代表前一个事件的坐标。 
5. 从一个活动位置移动时`x`到下一个，间隔$[last, x]$恒定覆盖范围等于`active`。 我们添加它的长度$x - last$到与该覆盖级别对应的存储桶。 
6. 处理坐标处的事件`x`通过更新`active`：关闭事件递减，打开事件递增。 
7. 更新`last = x`并继续，直到处理完所有事件。 
8. 扫完之后，我们就有了数值`c[k]`以获得准确的覆盖率计数。 我们计算前缀和以获得`a[h] = c[0] + c[1] + ... + c[h-1]`。 

关键的不变量是在任意两个连续的事件坐标之间，活动段的集合不会改变。 因此，覆盖计数在该间隔上是恒定的，并且将其完整长度分配给单个存储桶是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, S, F = map(int, input().split())
    
    events = []
    
    for _ in range(n):
        b, e = map(int, input().split())
        l = max(b, S)
        r = min(e, F)
        if l >= r:
            continue
        events.append((l, 1))   # open
        events.append((r, -1))  # close
    
    # sort: coordinate asc, close (-1) before open (+1)
    events.sort(key=lambda x: (x[0], x[1]))
    
    # max possible overlap is n
    c = [0] * (n + 1)
    
    active = 0
    last = S
    
    for x, typ in events:
        if x > last:
            c[active] += x - last
            last = x
        
        active += typ
    
    # no more events, but interval may continue to F
    if last < F:
        c[active] += F - last
    
    # prefix sums for answers
    a = [0] * (n + 1)
    for i in range(n):
        a[i + 1] = a[i] + c[i]
    
    print(*a[1:])

if __name__ == "__main__":
    solve()
```该代码首先读取段并立即将它们剪切到相关范围。 这可以避免来自目标区间之外的错误贡献。 每个有效的剪辑片段恰好产生两个事件，并且这些事件按平局排序进行排序，以确保首先处理关闭事件。 

扫描保持活动段的数量。 每当扫描及时向前移动时，先前的活动计数就会用于将贡献长度累积到正确的存储桶中。 

一个常见的实现陷阱是忘记处理从最后一个事件位置到$F$。 该代码显式添加了此剩余间隔。 另一个微妙的问题是事件排序：使用`(x, typ)`有效是因为`-1 < +1`，保证正确的边界处理。 

## 工作示例

 考虑一个简单的情况，其中大段是$[0, 10]$和两个小部分是$[1, 5]$和$[3, 7]$。 

我们在剪辑后处理事件：

 | 活动位置| 类型 | 之前活跃 | 添加间隔 | 贡献桶 |
 | --- | --- | --- | --- | --- |
 | 0 | 开始 | 0 | - | - |
 | 1 | +1 | 0 | [0,1] 长度 1 | c[0] += 1 |
 | 3 | +1 | 1 | [1,3] 长度 2 | c[1] += 2 |
 | 5 | -1 | 2 | [3,5] 长度 2 | c[2] += 2 |
 | 7 | -1 | 1 | [5,7] 长度 2 | c[1] += 2 |
 | 10 | 10 结束 | 0 | [7,10] 长度 3 | c[0] += 3 |

 这显示了重叠计数如何在事件点之间保持恒定以及如何正确归因线的每个段。 

现在考虑边缘对齐：$[0, 5]$和$[5, 10]$在$[0, 10]$。 

| 活动位置| 类型 | 之前活跃 | 添加间隔 | 贡献桶 |
 | --- | --- | --- | --- | --- |
 | 0 | +1 | 0 | [0,5]| c[1] += 5 |
 | 5 | -1 然后+1 | 1→0→1 | [5,10] 正确分割 | c[1] += 5 |

 处理在打开之前关闭可确保第 5 点不会重复计算。

 ## 边缘情况

 一个重要的边缘情况是完全位于大区间之外的线段。 例如，$[1, 5]$和$[S, F] = [10, 20]$。 裁剪后，间隔变空并被丢弃，因此不会创建任何事件，并且覆盖率始终保持为零。 

另一种情况是之前开始的段$S$并在内部结束，例如$[0, 7]$和$[S, F] = [5, 10]$。 剪裁后就变成了$[5, 7]$，并且仅在 5 和 7 之间起作用。扫描正确地从 5 开始计数，而不是从 0 开始计数。 

最后一个微妙的情况是多个段共享端点。 认为$[0, 5]$,$[5, 10]$， 和$[5, 8]$。 排序规则确保 5 处的关闭事件在打开之前得到处理，因此正好 5 处的重叠计数反映了边界每一侧的正确活动段集，从而避免了覆盖范围中的人为峰值。
