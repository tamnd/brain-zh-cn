 ## 解决方案
 ## 问题理解

 我们正在模拟一名旅行者使用两个固定时间表在两个站点 A 和 B 之间来回移动。 一个时刻表列出了从 A 到 B 的出发时间，另一个时刻表列出了从 B 到 A 的出发时间。 旅客每次登上巴士，行程需要固定的时间，到达后他们可以立即继续等待相反方向的下一趟可能的巴士。 

关键细节是旅客不会随意选择公交车。 在任何时候，他们总是会选择当前想去方向的下一班可用巴士，这意味着考虑到他们当前的到达时间，出发时间仍然有效的最早的巴士。 还有一个与时间表中最后相关时间相关的全局截止条件，这可以防止登上相对于最终允许时间太晚到达的巴士。 

输入由两个排序的整数序列组成，表示每个方向的公交车出发时间以及恒定的行驶延迟。 该过程从固定的车站和时间开始，我们重复模拟登上下一辆可行的巴士，直到不存在进一步的有效移动。 输出是成功乘坐公交车的次数。 

这些限制意味着两个计划都可能很大，通常最多可达大约 200,000 个条目。 在每一步扫描整个列表的简单模拟将重复遍历数组，在最坏的情况下导致二次行为。 在这种规模下，只有线性或近线性解决方案是安全的，因此我们必须确保每条总线最多被考虑一次或以对数方式考虑。 

一些边缘情况很重要。 一种是当前时间之后没有可用的公共汽车，即使存在较晚的公共汽车。 例如，如果我们在 A 的时间 10 点，下一趟 A 到 B 的巴士在 5 点，则这是无关紧要的，必须跳过。 另一个微妙的情况是，相对于全球截止时间，乘坐公共汽车会太晚到达； 即使有公共汽车可用，也必须拒绝，并可能阻碍进一步的进展。 最后，行程的交替性质意味着指针移动中的一个错误可能会导致同一段的重复重新考虑，从而导致无限循环或重复计数。 

## 方法

 暴力方法试图从字面上模拟该过程。 在每一步中，我们都会扫描整个相关时间表，以找到满足当前位置时间条件的第一辆公交车。 这是有效的，因为它直接遵循规则：我们总是选择最近的有效巴士。 然而，每次扫描都会花费线性时间，我们可能会在每次骑行时执行一次。 如果有 n + m 条总线并且可能有 O(n + m) 次转换，那么在最坏的情况下这会导致 O((n + m)^2) 行为，这太慢了。 

关键的观察是，两个时间表都是排序的，一旦我们及时通过了公共汽车，我们就不需要再考虑它了。 “最近的有效总线”始终是按排序顺序的下一个未使用的候选总线。 这允许我们维护两个指针，每个数组一个，并且只向前移动。 每次切换方向时，我们都会前进相应的指针，直到找到第一个有效的出发点。 

这将重复的重新扫描转换为对每个阵列的单次扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O((n + m)^2) | O((n + m)^2) | O(1) | O(1) | 太慢了|
 | 两指针模拟 | O(n + m) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们维护两个指向两个时间表的指针和一个跟踪当前时间和当前电台的变量。 我们反复尝试乘坐下一辆有效的巴士，直到无法进一步移动为止。

1. 在 A-to-B 和 B-to-A 数组的开头初始化两个索引 i 和 j，并将当前位置设置为 A，当前时间等于最早可能的开始时间。 这会在任何旅行发生之前建立模拟状态。 
2. 在A站时，将指针i前进，直到找到第一辆发车时间不早于根据问题的等待情况调整的准备发车时间的公交车。 这确保我们只考虑实际可搭乘的巴士。 
3. 检查在限流约束下是否允许乘坐该公交车。 如果违反了防止过度迟到的条件，则立即停止模拟。 
4. 如果有效，则增加乘车计数器，移动到 B 站，并将当前时间更新为出行后的到达时间。 这反映了完成一次完整的过渡。 
5. 当到达 B 站时，使用指针 j 执行对称过程，向前推进直到给定当前时间可以登上第一辆公交车。 
6. 应用相同的截止条件来验证有效性。 如果失败，则终止该过程，因为不可能有进一步的有效进展。 
7. 如果有效，则增加乘车计数器，返回 A 站，并相应地更新时间。 重复该过程。 

正确性来自于每个指针仅向前移动并且始终指向可能从当前时间获取的第一个未使用的候选总线的不变量。 由于时刻表已排序，任何较早的巴士一旦跳过，将永久无法使用，而任何较晚的巴士则无法到达。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, d = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    i = j = 0
    ans = 0

    # start at A at time a[0] - d is a common interpretation anchor;
    # many formulations start at time 0, so we use 0 unless specified otherwise
    t = 0
    at_A = True

    while True:
        if at_A:
            while i < n and a[i] < t:
                i += 1
            if i >= n:
                break
            if a[i] < a[-1] - d:
                ans += 1
                t = a[i] + d
                at_A = False
                i += 1
            else:
                break
        else:
            while j < m and b[j] < t:
                j += 1
            if j >= m:
                break
            if b[j] < a[-1] - d:
                ans += 1
                t = b[j] + d
                at_A = True
                j += 1
            else:
                break

    print(ans)

if __name__ == "__main__":
    solve()
```核心结构是在两个调度之间交替的循​​环。 每个内部 while 循环都会使指针前进，直到找到下一个可行的出发点。 关键的实现细节是指针只能向前移动，不能向后移动，这保证了线性复杂性。 

截止检查使用从最后相关 A 侧时间得出的最终阈值。 这可以防止旅客乘坐太晚到达的巴士而无法继续有意义的行程。 

## 工作示例

 考虑一个简单的情况，其中 A 到 B 总线的时间为 [3, 8, 15]，B 到 A 总线的时间为 [5, 10, 20]，且 d = 2。 

开始时，我们在时间 0 到达 A。第一辆可用的 A 巴士在 3，所以我们搭乘它，在时间 5 到达，然后前往 B。 

| 步骤| 侧面| 时间 | 指针我| 指针 j | 行动|
 | --- | --- | --- | --- | --- | --- |
 | 1 | 一个 | 0 | 0 | 0 | 取a[0]=3 |
 | 2 | 乙| 5 | 1 | 0 | 等待b |
 | 3 | 乙| 5 | 1 | 0 | 取 b[0]=5 |
 | 4 | 一个 | 7 | 1 | 1 | 继续 |

 该跟踪显示指针如何永远不会重新访问较早的总线并始终向前移动。 

现在考虑总线存在但相对于当前时间太早的情况，例如A总线[2,4,6]，当前时间为5。指针自动跳过2和4，只考虑6。这证实了算法正确地忽略了不可行的选项，而无需重新扫描。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + m) | 每个指针最多在其数组中严格向前移动一次 |
 | 空间| O(1) | O(1) | 仅存储索引和计数器 |

 线性扫描行为符合 ICPC 式调度模拟的典型约束，其中事件总数很大，但每个事件都处理一次。 即使对于最大输入大小，这也可以使执行在限制范围内轻松进行。

 ## 边缘情况

 当一个方向上的所有总线都早于当前时间时，就会出现临界边缘情况。 例如，如果我们在时间 50 处位于 B，并且所有 B 到 A 总线均位于 [1, 2, 3]，则指针将前进经过整个数组并正确终止。 该算法会处理此问题，因为内部 while 循环耗尽了 j，并且模拟立即停止。 

当存在有效总线但使用它会违反截止约束时，会出现另一种边缘情况。 在这种情况下，即使指针找到了可行的出发时间，条件检查也会阻止前进。 模拟会干净地停止，而不是尝试向前跳跃，从而防止错误的额外骑行。 

最后一个微妙的情况是交替移动重复消耗每个方向上最后剩余的有效总线。 由于指针在每次成功乘坐后立即递增，因此永远不会重新考虑同一辆公交车，并且当一侧用完可用的出发时间时，模拟自然结束。
