 ## 解决方案
 ## 问题理解

 该问题要求我们构建一个二叉树的集合，这些二叉树在特定意义上都是平衡的。 非空树由两个子指针表示。 一片叶子是一棵没有子树的树，它的大小是一，因为它贡献了一片叶子。 其他所有树的大小都等于其两个子树的大小之和。 

如果两个子子树大小相等或者左子树恰好比右子树大一个叶子，则树是有效的。 对于给定的叶子目标数量，我们需要输出一小组可重用的树，以便其中一个具有恰好那么多的叶子。 输出不是最终的树本身，而是内存表示，其中每个创建的树都可以引用先前创建的树。 

目标值可以大到$10^{18}$，所以构建整棵树是不可能的。 具有这么多叶子的正常平衡二叉树将大致包含$10^{18}$节点。 仅创建 125 棵树的限制告诉我们，预期的解决方案必须重用相同的子树并构造有向无环图而不是完整的树。 

重要的观察是，每次我们分裂一棵树，大小都会变成原始值的一半左右。 值为$10^{18}$大约经过 60 次减半后达到 1，因此递归结构的深度非常小。 挑战不是深度，而是确保我们不会为子树的每次出现创建一个单独的对象。 

当多次构建同一子树时，粗心的实现可能会失败。 例如，如果我们通过独立扩展两个子节点来构造目标值 16，我们将创建大小为 8 的树的两个副本，然后创建大小为 4 的四个副本，节点数量呈指数增长。 正确的输出只需要每种尺寸的一种表示。 对于输入值 16，一个有效输出可以为大小为 16 的树的两个子树重复使用相同的索引。 

另一个边缘情况是最小的可能目标。 对于输入：```
1
```正确的结构只是一片叶子：```
1
-1 -1
0
```假设每棵树都有两个子树的解决方案将错误地尝试引用不存在的节点。 

第二个边缘情况是奇数个叶子。 对于输入：```
5
```根必须分裂为尺寸 3 和 2。尺寸 3 的树必须分裂为 2 和 1。构造必须尊重左侧不能小于右侧。 像 2 和 3 这样的分割在数学上代表一个有效的平衡二叉树，但它违反了子项大小所需的排序。 

## 方法

 直接的方法是显式地构造整个平衡树。 从所需的叶子数开始，我们将其分成两半，递归地构建左右子树，并将它们连接起来。 这是可行的，因为选择两个子树大小作为当前大小一半的上限和下限始终满足平衡条件。 

问题是叶子的数量就是最终树中对象的数量。 如果答案需要$N$叶子，显式树有$O(N)$节点。 和$N$达到$10^{18}$，甚至存储答案也是不可能的。 

关键的观察结果是输出格式允许共享。 大小为 1000 的树不需要每次出现时都包含大小为 500 的树的新副本。 它可以指向同一棵已经创建的树。 平衡分割仅取决于当前大小，因此每种大小都有一种自然表示。 我们可以通过大小来记忆结构。 

暴力破解之所以有效，是因为递归分割创建了正确的树，但由于重复了相同的子树，所以会失败。 观察到状态只是叶子的数量，我们可以将整个结构简化为找到通过重复取两半而生成的所有不同值。 

不同尺寸的数量很少。 每次递归调用都会减少大约一半的大小，因此最多有 60 级左右。 每个级别最多可以贡献两个不同的值，远远少于允许的 125 棵树。

 ## 算法演练

 1. 从目标叶子数量开始。 如果为 1，则创建单个叶节点，表示为`(-1, -1)`。 这是唯一的基本情况，因为叶子已经是有效的平衡树。 
2.对于尺寸`x`大于1，将其分解为`left = (x + 1) / 2`和`right = x / 2`。 当大小为奇数时，左侧接收额外的叶子，与有效树的定义匹配。 
3. 递归地构建表示`left`和`right`。 在创建新树之前，检查是否已经构建了该大小的树。 如果是，则重用其索引。 子树的状态完全由其叶子计数来描述。 
4. 将这对子索引存储为当前大小的表示。 分配给该表示的索引稍后可以由更大的树使用。 
5.构造完目标大小后，输出所有创建的树以及目标树的索引。 

为什么它有效：

 对于每个构造尺寸`x`，该算法创建具有大小的子项`ceil(x/2)`和`floor(x/2)`。 这两个值最多相差一，并且较大的值总是放在左边，因此每棵创建的树都满足平衡规则。 由于较大的尺寸仅与较小的已有效尺寸相关，因此正确性从叶情况递归得出。 

共享不会改变所表示的树结构。 每个引用仍然指向具有所需叶子数量的有效子树。 记忆仅避免打印重复的定义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    memo = {}
    nodes = []

    def build(x):
        if x in memo:
            return memo[x]

        if x == 1:
            idx = len(nodes)
            nodes.append((-1, -1))
            memo[x] = idx
            return idx

        left_size = (x + 1) // 2
        right_size = x // 2

        left = build(left_size)
        right = build(right_size)

        idx = len(nodes)
        nodes.append((left, right))
        memo[x] = idx
        return idx

    root = build(n)

    out = []
    out.append(str(len(nodes)))
    for a, b in nodes:
        out.append(f"{a} {b}")
    out.append(str(root))

    print("\n".join(out))

t = int(input())
for _ in range(t):
    solve()
```这`memo`字典存储从叶计数到其构造树的索引的映射。 这是核心优化。 如果没有它，递归将重复重建相同的一半。 

基本情况使用插入叶表示`-1`为了两个孩子。 每个其他调用首先创建较小的树，然后附加一个指向这些现有索引的新节点。 

分割仔细地使用整数运算。`(x + 1) // 2`是天花板的一半并且`x // 2`是地板的一半。 这使得左孩子至少与右孩子一样大。 

生成的节点数量仍然很小，因为唯一生成的大小是重复将目标减半时遇到的值。 即使对于最大的输入，唯一状态的数量也远低于 125 个。

 ## 边缘情况

 对于最小情况`N = 1`，算法立即返回叶节点。 不需要子索引，因此输出有效。 

对于奇数值，例如`N = 5`，根由大小为 3 和 2 的子节点创建。大小为 3 的树由子节点 2 和 1 创建。每次拆分都将较大的部分保留在左侧，因此满足排序要求。 

对于较大的值，例如`N = 10^18`，递归从不尝试创建$10^{18}$节点。 它仅创建由减半产生的不同大小的链。 最终的结构是可重用平衡树的小图，而不是巨大的扩展树。
