 ## 解决方案
 ## 问题理解

 我们有一块圆板，上面有$N$位置标记为$0$到$N-1$。 一名球员从某个位置开始$Y$。 还有一系列长度的移动$K$，每一步都会增加一个值$a_i$到当前位置，但所有位置均取模$N$，因此玩家始终留在圆圈内。 

扭曲的是一个特定的正方形$X$行为就像一个门户。 每当玩家落地时$X$完成一个动作后，他们不会像平常那样停留在那里。 相反，他们立即“传送”到$Y$，然后继续应用未来的移动$Y$再次。 

任务是确定每个起始方格$z$，玩家应用所有内容后最终会到达的位置$K$在此传送规则处于活动状态时移动。 

天真的解释是简单的模拟：尝试从每个$z$，模拟所有动作，并且每当$X$到达后，跳转回$Y$。 问题在于，直接模拟重复工作量很大，因为为每个起始位置重新计算相同的前缀和和传送周期。 

约束条件意味着$N$和$K$足够大，任何$O(NK)$模拟速度太慢。 甚至$O(K)$当对所有查询重复时，每个查询的起始位置将是不可行的$N$州。 

反复访问时出现了一个微妙的问题$X$。 例如，如果前缀和使步行命中$X$多次，那么第一次命中后的未来行为仅取决于下一次命中的时间，而不是完整路径。 不重用重复结构的简单方法会多次重新计算相同的后缀行为。 

另一个边缘情况是当$X$从给定的开始根本就没有达到。 在这种情况下，就没有隐形传态，结果只是简单的模块化前缀和移位。 任何解决方案都必须清楚地区分这两种情况。 

## 方法

 蛮力方法独立模拟每个起始位置。 对于每个$z$，我们迭代所有$K$移动，保持当前位置，并且每当我们着陆时$X$，我们重置为$Y$。 这是正确的，因为它完全遵循规则。 然而，相同的前缀和被重新计算$N$次，导致$O(NK)$时间复杂度，当两者都存在时，时间复杂度太慢$N$和$K$很大。 

关键的观察是，圆上的运动仅取决于前缀和模$N$。 如果我们定义$p_i = (a_1 + \dots + a_i) \bmod N$，那么之后的位置$i$从头开始移动$z$是$z + p_i$unless a teleport resets the process.

 重要的结构是达到$X$仅取决于求解模条件：$$z + p_i \equiv X \pmod N$$这相当于$$p_i \equiv X - z \pmod N$$所以对于每个残基$d$，我们想知道最早的时间$i$在哪里$p_i \equiv d$。 一旦我们知道第一次发生，我们就可以确定传送是否发生，如果发生，该过程如何继续$Y$。 

第二个关键见解是，一旦我们着陆$X$在某个索引处$i$，最终结果仅取决于之后发生的情况$i$，再次从$Y$。 这会在前缀索引上创建一个“跳转表”：每个第一次命中要么导致后来的递归命中，要么干净地终止。 

我们从右到左预处理前缀和，存储每个残基的最早索引。 这使我们能够在每次查询的恒定时间内计算下一次传送发生在哪里，或者是否没有发生。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(NK)$|$O(1)$| 太慢了|
 | 最佳|$O(N + K)$|$O(N)$| 已接受 |

 ## 算法演练

 我们使用移动数组模的前缀和$N$。 让$p_i$表示到索引的前缀总和$i$， 和$p_0 = 0$。 

然后，我们为每个残基类别计算它出现的最早位置。 这为我们提供了一种直接的方式来回答“我们下次什么时候登陆”$X$”从任何移动的起点。

 ## 算法演练

 1. 计算前缀和$p_i = (a_1 + \dots + a_i) \bmod N$。 这将运动压缩为模块化位置，因此每个未来位置都可以写成前缀值的简单相加。 
2. 构建数组`idx[d]`存储最小的索引$i$这样$p_i \equiv d \pmod N$。 我们通过从末尾扫描来填充它，以便较早的索引覆盖较晚的索引。 这保证了我们始终存储第一次出现的情况。 
3. 对于固定起点$z$, 着陆条件$X$在步骤$i$变成$p_i \equiv X - z$。 我们将其转换为查找`idx[(X - z) mod N]`。 
4. 如果该索引不存在，则不会发生传送。 最终的位置很简单$z + p_K \bmod N$。 
5. 如果索引存在，假设第一次命中位于$i$。 从那一刻起，我们重新设定$Y$，所以问题简化为计算从$Y$但只考虑后缀行为$i$。 我们预先计算`end[i]`，如果我们第一次点击，它会存储最终结果$X$搬家后$i$。 
6. 计算`end[i]`，我们要么发现下一次相同的残留条件再次发生，要么得出结论，不再发生传送。 这是使用相同的方法完成的`idx`结构，确保我们总是跳到下一个相关事件。 
7. 最后，对于每个起始位置$z$，我们输出第一个命中索引的后缀结果，或者如果不存在命中则输出简单线性结果。 

这样做的原因是每次传送后，系统都会重置为固定状态$Y$，之后唯一重要的是前缀和的剩余后缀。 前缀和的结构使得未来的命中仅取决于模相等，这已经完全编码在`idx`桌子。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, K, X, Y = map(int, input().split())
    a = list(map(int, input().split()))

    p = [0] * (K + 1)
    for i in range(1, K + 1):
        p[i] = (p[i - 1] + a[i - 1]) % N

    INF = K + 5
    idx = [INF] * N

    for i in range(K, -1, -1):
        idx[p[i]] = i

    end = [0] * (K + 1)

    for i in range(K, -1, -1):
        d = p[i]
        nxt = idx[d]
        if nxt == INF:
            end[i] = (Y + p[K] - p[i]) % N
        else:
            if nxt == i:
                end[i] = (Y + p[K] - p[i]) % N
            else:
                end[i] = end[nxt]

    res = [0] * N

    for z in range(N):
        d = (X - z) % N
        i = idx[d]
        if i == INF:
            res[z] = (z + p[K]) % N
        else:
            res[z] = end[i]

    print(*res)

if __name__ == "__main__":
    solve()
```解决方案首先构建前缀和模$N$，它将所有运动转换为固定周期上的模运算。 这`idx`数组是从后开始构建的，以便每个残基存储它最早出现的时间。 

这`end`然后通过索引向后计算数组。 每个`end[i]`代表最终结果，如果第一次着陆$X$移动后立即发生$i$。 如果不再出现相同的残基，则该过程只需从后缀直接移位即可结束$Y$。 否则，我们会重用已经计算的结果，这就是保持复杂性线性的原因。 

最后，每个起始位置$z$映射到所需的残基$X - z$，我们要么跳进预先计算的`end`状态或退回到纯前缀和翻译​​。

 ## 边缘情况

 一种边缘情况是当$X$从每个起始位置都无法到达。 在这种情况下，所有条目`idx[X - z]`不存在，因此每个结果都回落到简单的模和$z + p_K$。 该算法干净地处理了这个问题，因为查找立即分支到非传送情况。 

另一个边缘情况是前缀和从不重复残数。 然后`idx[d]`始终指向唯一索引，并且`end[i]`永远不会穿过另一个状态。 这将系统减少为独立的线性后缀计算，这与预期的行为相匹配。 

第三种边缘情况是当$K = 0$。 然后$p_0 = 0$,`idx`仅包含索引 0 处的残基 0，并且每个起始位置都直接映射到$X$或保持不变。 该算法仍然有效，因为所有逻辑都简化为前缀结构中的恒定时间查找。
