 ## 解决方案
 ## 问题理解

 每种颜色都是两个玩家都拥有的独立弹珠堆。 一步棋选择双方仍然存在的颜色。 

假设颜色`i`是由爱丽丝选择的。 爱丽丝正好扔掉了她那个颜色的一颗弹珠，而鲍勃则丢掉了所有弹珠`b_i`那种颜色的弹珠。 在那一步之后，鲍勃的彩色弹珠为零`i`，这样就再也无法播放该颜色了。 

同样，如果鲍勃选择颜色`i`，鲍勃失去了一颗弹珠，爱丽丝失去了所有弹珠`a_i`那种颜色的弹珠。 

因为任何选择的颜色立即变得永远不可用，所以每种颜色最多播放一次。 游戏实际上是决定谁获得每种颜色最终分辨率的所有权。 

最终得分为$$\text{Alice's remaining marbles} - \text{Bob's remaining marbles}.$$Alice 希望这个值尽可能大，Bob 希望它尽可能小。 

简单版本有`n ≤ 6`。 那是非常小的。 即使尝试所有可能的移动顺序也是可行的，因为颜色的数量很少。 游戏状态的数量增长大致如下`n!`，这对于`n = 6`只是`720`。 至多有`1000`测试用例中，完整的极小极大搜索仍然非常快。 

最常见的错误是认为颜色是独立的并且可以单独优化。 但事实并非如此，因为回合顺序决定了谁能获得某种颜色。 

考虑：```
n = 2
a = [100, 1]
b = [1, 100]
```如果 Alice 得到颜色 1，Bob 得到颜色 2，则结果与反向分配有很大不同。 回合的竞争就是整个游戏。 

另一个容易犯的错误是只评估比赛过程中移除的弹珠，而不是最终剩余的弹珠。 

例如：```
n = 1
a = [5]
b = [7]
```如果 Alice 选择唯一的颜色，她会失去 1 个弹珠，而 Bob 会失去全部 7 个弹珠。最终状态是：```
Alice: 4
Bob: 0
```分数是`4`， 不是`7 - 1 = 6`。 游戏由剩余的弹珠来定义。 

第三个微妙之处是，任何一个玩家选择的颜色都会永远消失。 

例子：```
a = [10]
b = [10]
```Alice 玩完该颜色后，Bob 以后就不能玩同样的颜色了。 任何允许多种使用一种颜色的解决方案都是对不同的游戏进行建模。 

## 方法

 因为`n`最多是六，最直接的方法是极小极大。 

在任何状态下，我们都知道哪些颜色仍然可用。 如果轮到爱丽丝，她会尝试每种可玩的颜色并选择产生最大最终分数的移动。 如果轮到鲍勃，他会选择最小的最终分数。 

挑战在于有效评估最终状态。 

一个有用的观察是，一旦我们知道谁拥有每种颜色，每种颜色就会独立贡献。 

假设颜色`i`从未播放过。 那么它对最终得分的贡献就是$$a_i - b_i.$$假设爱丽丝玩颜色`i`。 

爱丽丝保留`a_i-1`弹珠和鲍勃保持`0`，因此贡献变为$$(a_i-1)-0 = a_i-1.$$与未受影响的贡献相比`a_i-b_i`，分数变化为$$(a_i-1)-(a_i-b_i)=b_i-1.$$同样，如果鲍勃玩颜色`i`，贡献变为$$0-(b_i-1)=-(b_i-1),$$这与未受影响的贡献不同$$-(b_i-1)-(a_i-b_i)=-(a_i-1).$$这让我们可以将游戏完全表达为根据所选颜色累积收益和损失。 

然而，对于简单的版本，我们实际上并不需要复杂的贪心论证。 状态空间很小，因此子集上的记忆极小极大就足够了，并且很容易证明正确。 

蛮力之所以有效，是因为每一步都会永久去除一种颜色。 最多六步后游戏结束。 州总数仅为$$2^6 \times 2 = 128.$$记忆化使得搜索基本上是即时的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 无需记忆的蛮力极小极大 | O(n!) | O(n) | 接受简单版本，但多余的工作 |
 | 子集上的记忆极小极大 | O(n·2^n) | O(n·2^n) | O(2^n) | O(2^n) | 已接受 |

 ## 算法演练

 让`base`如果没有播放任何颜色，则为分数：$$base = \sum (a_i-b_i).$$我们将仅计算由所播放的颜色引起的额外变化。 

对于一种颜色`i`:$$gainAlice_i = b_i - 1$$因为爱丽丝选择它会增加相对于`base`。$$gainBob_i = -(a_i - 1)$$因为鲍勃选择它会使分数相对于`base`。 

我们通过已使用颜色的位掩码以及轮到谁来定义 DP 状态。 

### 1. 计算基本分数

 全部加起来`a_i - b_i`。 

这是在考虑任何所打颜色之前的分数。 

### 2. 用位掩码表示游戏状态

 位`i`如果颜色被设置`i`已经被某人选择了。 

每一步都恰好设置一个先前未设置的位。 

### 3.定义极小极大函数

 让```
dp(mask, turn)
```是从当前状态开始的最佳分数调整。`turn = 0`意味着爱丽丝接下来要移动。`turn = 1`意味着鲍勃接下来要移动。 

### 4. 处理终端状态

 如果每种颜色都已使用，则无法进一步调整。 

返回`0`。 

### 5.爱丽丝的转变

 爱丽丝尝试了每种未使用的颜色`i`。 

选择颜色`i`立即贡献$$b_i-1.$$之后游戏从新面具和鲍勃的回合开始继续。 

Alice 在所有选项中选择最大值。 

### 6.鲍勃的转变

 鲍勃尝试了每种未使用的颜色`i`。 

选择颜色`i`立即贡献$$-(a_i-1).$$然后游戏从新面具和爱丽丝的回合开始继续。 

鲍勃选择所有选项中的最小值。 

### 7. 与基础分数结合

 答案是$$base + dp(0,\text{Alice turn}).$$### 为什么它有效

 关键属性是每种颜色最多只能选择一次。 一旦玩家选择了一种颜色，该颜色就会从游戏中永久消失。 因此，未来的状态仅取决于已经使用了哪些颜色以及轮到谁使用。 

一步棋的贡献在选择颜色的那一刻就完全确定了。 以后发生的任何事情都不会再次改变该颜色。 最小最大递归完全符合最佳游戏规则：爱丽丝最大化最终得分，鲍勃最小化它。 由于每个合法的延续都会被探索和记忆，计算值等于真实的游戏值。 

## Python 解决方案```python
import sys
from functools import lru_cache

input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        base = sum(ai - bi for ai, bi in zip(a, b))
        full = (1 << n) - 1

        @lru_cache(None)
        def dp(mask, turn):
            if mask == full:
                return 0

            if turn == 0:  # Alice
                best = -10**30
                for i in range(n):
                    if not (mask & (1 << i)):
                        best = max(
                            best,
                            (b[i] - 1) + dp(mask | (1 << i), 1)
                        )
                return best

            else:  # Bob
                best = 10**30
                for i in range(n):
                    if not (mask & (1 << i)):
                        best = min(
                            best,
                            -(a[i] - 1) + dp(mask | (1 << i), 0)
                        )
                return best

        ans.append(str(base + dp(0, 0)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```解决方案首先计算未触及的分数`base`。 然后，每一步都变成相对于该基线的简单调整。 

DP 状态仅包含使用的颜色遮罩和要移动的玩家。 无需存储弹珠数量，因为颜色的整体效果在选择后就已确定。 

爱丽丝的转变增加了`b[i] - 1`。 鲍勃的转变增加了`-(a[i] - 1)`。 这些值直接来自于将某种颜色播放后的分数与该颜色保持不变时的分数进行比较。 

递归深度永远不会超过`n`，最多为 6，因此递归是完全安全的。 

## 工作示例

 ### 示例 1```
n = 3
a = [4, 2, 1]
b = [1, 2, 4]
```基础分数：$$(4-1)+(2-2)+(1-4)=0$$调整值：

 | 颜色 | 爱丽丝增益| 鲍勃·增益 |
 | --- | --- | --- |
 | 1 | 0 | -3 |
 | 2 | 1 | -1 |
 | 3 | 3 | 0 |

 最佳玩法：

 | 转 | 玩家| 颜色 | 立即改变 | 跑步调整|
 | --- | --- | --- | --- | --- |
 | 1 | 爱丽丝| 1 | 0 | 0 |
 | 2 | 鲍勃 | 3 | 0 | 0 |
 | 3 | 爱丽丝| 2 | +1 | 1 |

 最终成绩：```
base + adjustment = 0 + 1 = 1
```这个例子表明，立即增益为零的动作仍然是最佳的，因为它可以防止对手获得更有价值的颜色。 

### 示例 2```
n = 4
a = [1, 20, 1, 20]
b = [100, 15, 10, 20]
```基础分数：$$(1-100)+(20-15)+(1-10)+(20-20)=-103$$调整值：

 | 颜色 | 爱丽丝增益| 鲍勃·增益 |
 | --- | --- | --- |
 | 1 | 99 | 99 0 |
 | 2 | 14 | 14 -19 | -19
 | 3 | 9 | 0 |
 | 4 | 19 | 19 -19 | -19

 一种最佳序列是：

 | 转 | 玩家| 颜色 | 立即改变 | 跑步调整|
 | --- | --- | --- | --- | --- |
 | 1 | 爱丽丝| 1 | 99 | 99 99 | 99
 | 2 | 鲍勃 | 4 | -19 | -19 80|
 | 3 | 爱丽丝| 2 | 14 | 14 94 | 94
 | 4 | 鲍勃 | 3 | 0 | 94 | 94

 最终成绩：```
-103 + 94 = -9
```这条轨迹展示了两个玩家如何争夺相同的颜色池，而不是独立地最大化局部收益。

 ## 边缘情况

 考虑对称位置：```
1
2
5 5
5 5
```每种颜色都有爱丽丝增益`4`和鲍勃增益`-4`。 爱丽丝选择一种颜色，鲍勃选择另一种颜色。 调整完全取消，给出最终分数`0`。 DP探索了这两种可能性并达到了相同的结果。 

现在考虑：```
1
2
100 1
1 100
```未触及的分数为零。 Alice 增益值为`[0, 99]`，而鲍勃的增益值为`[-99, 0]`。 爱丽丝立即声称第二个颜色的价值`99`。 鲍勃被迫拿走剩余的颜色`-99`。 答案就变成了`198`。 任何仅基于当前弹珠总数的贪婪规则很容易错过这种交互，但极小极大可以自然地处理它。 

最后，考虑一侧有大量弹珠的颜色：```
1
2
1000000000 1
1 1
```分数调整涉及接近的值`10^9`。 Python 整数具有任意精度，因此不会发生溢出。 DP 准确存储并组合这些值，产生正确的最佳分数。
