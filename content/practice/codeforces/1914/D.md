 ## 解决方案
 ## 问题理解

 每个测试用例给出三个长度相等的数组，其中每个索引代表假期期间的一天。 在任何一天，Monocarp 都有三个独立的“选项”：如果他那天去滑雪，有多少朋友会加入，那天有多少朋友会加入看电影，以及那天有多少朋友会加入棋盘游戏。 

关键的限制是他必须选择三个不同的日子，每个活动都选择一个日期。 目标是将滑雪、电影和棋盘游戏分配给三个不同的指数，以使相应值的总和最大化。 

因此，问题不在于独立选择三个最佳个体值。 每个值都与一天相关，唯一的限制是任何两个活动都不能使用相同的索引。 

每个测试用例的输出都是一个数字：使用三个不同的索引从三个数组中的每一个中获取的一个值的最大可实现总和。 

限制很大：所有测试用例的总天数最多可达 100,000 天。 这立即排除了每个测试用例的任何三次甚至二次方法。 任何尝试所有三倍天甚至所有成对作业的方法都太慢了。 每个测试用例的解决方案必须本质上是线性的或线性的。 

当三个数组中的最大值碰巧位于同一索引上时，就会出现一个微妙的陷阱。 从每个数组中独立选取最大值的天真贪婪方法将会失败，因为它违反了不同日约束。 例如：

 输入：```
1
3
10 1 1
10 1 1
10 1 1
```一个简单的解决方案会从所有三个数组中选择 10 个，总和为 30，但这是不可能的，因为所有三个最大值都出现在第一天。正确的答案是 10 + 1 + 1 = 12，通过将选择分布在不同的索引上。 

这表明了核心困难：我们必须在选择大值的同时确保指数不发生冲突之间取得平衡。 

## 方法

 蛮力的想法很简单。 我们尝试三个不同日期 x、y、z 的每一个选择并计算 a_x + b_y + c_z。 这是正确的，因为它枚举了所有有效的分配，但它太慢了。 当 n 达到 100,000 时，三元组的数量约为 n^3，在最坏的情况下约为 10^15 次运算。 

我们需要减少问题结构。 关键的观察是选择之间的唯一耦合是索引相等。 如果我们可以忽略碰撞，我们只需独立地取每个数组的最大值即可。 整个困难在于确保同一个索引不会被多次使用。 

这建议进行结构性重构：我们不再考虑三个独立的最大值，而是考虑有多少选定值来自重叠索引。 

只有几个有意义的结构案例：

 我们要么使用三个不同的指数作为最佳候选，要么一些最佳值在指数上发生冲突，我们必须将其中一个“转移”到第二佳选项。 由于冲突只在顶级候选者之间起作用，因此我们只需要检查每个数组的少量最佳元素。 

捕获此问题的标准方法是从每个数组中取出前几个候选者（例如前 3 个或前 5 个），并尝试从每个列表中选取一个元素的所有组合，同时确保索引不同。 这是可行的，因为任何最佳解决方案都必须涉及位于各自数组中最高的几个元素。 如果所选元素在其数组中的排名远远靠后，则用更高的未使用元素替换它只会改善或保留答案。 

因此，我们将问题简化为检查恒定大小的候选集。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解所有三元组 | O(n^3) | O(n^3) | O(1) | O(1) | 太慢了 |
 | 每个数组的前 k 个候选者 + 枚举 | O(n log n + k^3) | O(n log n + k^3) | O(n) | 已接受 |

 ## 算法演练

 1. 对于三个数组中的每一个，将每个值与其索引配对，并按值的降序排序。 这使我们能够快速识别最强的候选人，同时跟踪他们的职位。 
2. 从每个数组中提取前 k 个元素，其中 k 是一个小常数，例如 3 或 5。目的是确保我们不会错过任何最佳组合，即使它涉及避免最佳元素之间的索引冲突。 
3. 尝试从每个数组的 top-k 列表中选取一个元素的所有组合。 对于每个三元组，检查所选的三个索引是否不同。 如果不是，则丢弃该组合。 
4. 对于有效组合，计算三个值的总和并跟踪最大值。 
5. 输出找到的最佳值。 

枚举在这里安全的原因是任何最佳解决方案都必须使用靠近各自数组顶部的元素。 如果一个元素不在其数组的前几个元素中，则可以将其替换为更好的候选元素，除非该替换导致冲突，在这种情况下，可以通过切换到另一个附近的顶部候选元素来解决冲突。 这个局部性使得恒定大小的搜索就足够了。 

### 为什么它有效

正确性依赖于这样一个事实：我们只需要解决最高价值候选人之间的冲突。 由于除了索引冲突之外，每个数组都是独立的，因此最佳解决方案由三个高排序元素形成。 如果一个解决方案使用了其数组的前 k 个元素之外的元素，则用排名较高的未使用选项替换它永远不会减少总数，除非它产生索引冲突，并且解决该冲突只需要考虑顶级候选者的一小部分邻域。 这将搜索空间限制到每个数组的排序前缀的恒定区域。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        c = list(map(int, input().split()))

        k = 3  # small constant is enough in practice
        A = sorted([(a[i], i) for i in range(n)], reverse=True)[:k]
        B = sorted([(b[i], i) for i in range(n)], reverse=True)[:k]
        C = sorted([(c[i], i) for i in range(n)], reverse=True)[:k]

        ans = 0

        for av, ai in A:
            for bv, bi in B:
                for cv, ci in C:
                    if ai != bi and ai != ci and bi != ci:
                        ans = max(ans, av + bv + cv)

        print(ans)

if __name__ == "__main__":
    solve()
```该实现独立读取每个测试用例并构建三个排序的候选列表。 每个列表都存储值和索引，以便我们可以在枚举期间强制执行不同日期约束。 

嵌套循环仅迭代最多 3 × 3 × 3 的组合，这使得即使在最大输入大小下也能保持快速求解。 正确性取决于排序期间保留索引，以便我们可以拒绝无效的重叠。

 ## 边缘情况

 当所有三个数组在同一索引处达到峰值时，就会出现关键的边缘情况。 例如：```
1
3
100 1 1
100 1 1
100 1 1
```该算法收集所有数组的最佳候选，包括 (100,0)。 检查组合时，任何多次使用索引 0 的三元组都会被拒绝。 唯一有效的组合涉及将不同索引中剩余的较低值配对，产生 100 + 1 + 1 = 102。 

这表明该算法不假设最大值独立，而是明确强制索引分离，同时仍然优先考虑高值候选者。 

另一种边缘情况是当最佳解决方案使用次佳元素时，因为绝对最佳值发生冲突。 对 top-k 列表的枚举保证了这些替代方案存在并经过测试，确保解决方案不会在尝试强制无效的最大组合时陷入困境。
