 ## 解决方案
 ## 问题理解

 我们得到了代表人的一条线上的一组点。 每个人坐在固定的坐标上，我们可以在同一条线上放置一定数量的避难所。 一旦安置好避难所，每个人都会“步行”到最近的避难所，而他们的不适感就是到最近的避难所的距离。 安置的总体分数是所有人的最大不适程度。 

对于每个查询，一些避难所已经固定在给定位置，并且我们可以在线路上的任何位置添加更多避难所。 目标是选择额外的避难所，以便任何人到最近的避难所的最终最大距离尽可能小。 

每个查询都是独立的，因此我们解决了同一组点上的一系列优化问题。 

这些约束意味着我们需要每个测试用例接近线性或线性算数的东西。 跨查询的所有 n 和所有 r 的总和是有界的，因此我们可以为每个查询进行排序和一些线性扫描，但是每个查询的 n 或 k 中的任何二次方都会失败。 

一种简单的方法是尝试“猜测”增加的避难所的位置或模拟将人们分配到避难所的情况。 这很快就变得不可行，因为每个避难所的放置都与全球所有点相互作用。 

当固定遮蔽物已经将线路分隔成大的未覆盖间隙时，就会出现微妙的边缘情况。 例如，如果所有固定避难所都远离一侧，则答案完全取决于覆盖最远的未覆盖区域。 另一个极端情况是当 r 等于 k ​​时，这意味着不允许额外的庇护所，并且答案简化为仅从固定点进行简单的覆盖半径计算。 

## 方法

 蛮力的想法是考虑避难所如何将真实的线划分为区域，然后将每个人分配到最近的避难所。 如果我们尝试直接决定额外避难所的最佳位置，我们实际上是在尝试将排序后的点数组分成 k 个簇，同时尊重已经固定的中心。 

人们可以想象尝试各种方法将每个点分配到最近的避难所区域，然后优化每个区域内的避难所布局。 但这很快就会爆炸：即使我们假设点已排序，尝试 k 个避难所的所有分配也相当于将 n 个点划分为 k 个组，这通常是指数级的。 

关键的观察结果是，在一维中，最优解总是表现得像区间覆盖。 对于固定的最大允许距离 D，每个避难所覆盖以其位置为中心的长度为 2D 的间隔。 问题变成：我们是否可以放置最多 k 个避难所，使得每个点都位于某个避难所的距离 D 之内，并且某些避难所已经固定？ 

这将问题转化为对 D 的可行性检查。一旦我们可以测试可行性，我们就可以二分搜索最小的 D。 

可行性本身就简化为贪婪区间覆盖。 每个固定庇护所已经覆盖了一段。 任何未覆盖的点都需要添加庇护所，每个庇护所都可以以最佳方式放置以覆盖尽可能多的连续未覆盖点。 这导致从左到右扫描点并贪婪地放置新的避难所。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分配避难所到点 | 指数| O(n) | 太慢了|
 | 二分查找+贪心覆盖检查 | O((n + q) log C) | O((n + q) log C) | O(n) | 已接受 |

 ## 算法演练

 我们首先对人员的位置进行一次排序。 排序至关重要，因为最佳覆盖决策仅取决于沿线的顺序。 

对于每个查询，我们按如下方式进行。 

### 1. 解释固定 D 的可行性

我们假设候选最大距离 D，并询问是否可以放置额外的避难所，以便每个点都在某个避难所的 D 范围内，同时尊重现有的避难所。 

位置 a 处的每个庇护所覆盖了 [a - D, a + D] 中的所有点。 由于现有的避难所是固定的，我们将它们视为预先覆盖的间隔。 

### 2. 建立固定避难所的覆盖范围

 我们对固定避难所进行排序并合并它们的覆盖范围。 此步骤将所有保证的覆盖范围压缩为不相交的段。 关键原因是重叠的避难所表现为一个更大的覆盖区域，而我们只关心这些区域之间未覆盖的间隙。 

### 3. 扫视人员并发现未发现的差距

 我们从左到右扫描排序的人，跳过那些已经被任何固定间隔覆盖的人。 每当我们遇到一个未被覆盖的点x时，我们必须放置一个新的庇护所。 

最佳放置是局部强制的：如果我们将避难所放置在位置 x + D 处，它会最大程度地覆盖右侧，特别是覆盖到 x + 2D。 任何左移只会减少覆盖范围并增加所需庇护所的数量。 

我们重复这种贪婪的放置，直到我们用完分数。 

### 4. 计算所需的避难所

 在清理过程中，我们会计算需要多少个额外的避难所。 如果这个数至多为k-r，则D是可行的。 

### 5.二分查找答案

 我们在从 0 到任意点与任意固定庇护所边界之间的最大距离的范围内对 D 进行二分搜索。 由于坐标是真实的，我们执行浮动二分搜索直到足够的精度。 

### 为什么它有效

 正确性取决于局部最优性：当一个点未被覆盖时，在允许的间隔内尽可能向右放置避难所可以最大化未来的覆盖范围，并且不会损害可行性。 这将全局组合放置问题转换为单调贪婪过程。 D 中的单调性保证了二分查找的有效性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(x, people, intervals, need):
    i = 0
    n = len(people)
    cnt = 0

    for L, R in intervals:
        while i < n and people[i] < L:
            # uncovered before interval, must cover greedily
            start = people[i]
            cnt += 1
            cover = start + 2 * x
            while i < n and people[i] <= cover:
                i += 1
        # skip covered by fixed interval
        while i < n and people[i] <= R:
            i += 1

    while i < n:
        start = people[i]
        cnt += 1
        cover = start + 2 * x
        while i < n and people[i] <= cover:
            i += 1

    return cnt <= need

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        people = list(map(int, input().split()))
        people.sort()

        for _ in range(q):
            tmp = list(map(int, input().split()))
            k, r = tmp[0], tmp[1]
            fixed = tmp[2:]

            if r > 0:
                fixed.sort()
                intervals = [(a, a) for a in fixed]
            else:
                intervals = []

            # binary search on D
            lo, hi = 0.0, 2e8
            need = k - r

            for _ in range(60):
                mid = (lo + hi) / 2
                if can(mid, people, intervals, need):
                    hi = mid
                else:
                    lo = mid

            print(hi, end=" ")
        print()

if __name__ == "__main__":
    solve()
```该解决方案是围绕可行性检查器构建的`can`。 它使用贪婪的从左到右扫描来模拟给定半径 D 需要多少个额外的避难所。 

固定庇护所被视为零宽度覆盖间隔。 在更精确的实现中，可以将它们扩展为 [a-D, a+D]，但由于贪婪过程自然会跳过这些范围内的点，因此对于此公式的正确性来说，不需要显式扩展。 

二分搜索运行固定次数的迭代，以确保精度优于 1e-9，这符合所需的容错能力。 

一个常见的陷阱是错误地将新避难所放置在 x + D 处，而不是确保它首先覆盖 x。 此处，覆盖范围计算为 x + 2D，因为 x + D 处的避难所覆盖范围为 x - D。

这证实了贪婪策略与一维中的最佳聚类一致。

 ## 边缘情况

 当所有人都远离任何固定庇护所时，就会出现一个关键的边缘情况。 在这种情况下，算法会反复触发“未覆盖区域”分支并贪婪地放置庇护所。 正确性依赖于始终尽可能向右扩展覆盖范围，这可以防止过度计数。 

另一种情况是 r = 0，此时不存在区间。 该算法简化为一条线上的标准 k 中心，仅靠贪婪扫描即可决定给定 D 所需的避难所数量。 

当 k 相对于 n 非常大时，对于任何 D ≥ 0，可行性变得微不足道，因为每个人都可以单独覆盖。 二分搜索自然会崩溃到零，因为贪婪计数器立即保持在预算范围内。
