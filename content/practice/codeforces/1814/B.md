 ## 解决方案
 ## 问题理解

 机器人从原点开始，最初有腿长`1`。 在任何时刻，它都可以将其腿长增加一，或者沿着 x 轴或 y 轴精确地跳跃其当前腿长。 

目的地是`(a, b)`。 我们想要最少的动作总数，包括腿长的增加和跳跃。 

思考这个问题的一个有用方法是想象选择最终的腿长度`m`。 到达坐标`a`，每次水平跳跃都贡献了精确的`m`，所以我们至少需要`ceil(a / m)`水平跳跃。 同样，到达坐标`b`至少需要`ceil(b / m)`垂直跳跃。 

使用腿长前`m`，机器人必须从`1`到`m`，这需要花费`m - 1`移动。 

测试用例数量较少，但坐标值较大。 自从`a`和`b`可以大到`10^9`，任何对位置的状态空间搜索都是不可能的。 即使是与以下比例成比例的算法`a`或者`b`会太慢了。 我们需要最佳答案的数学特征。 

有一些容易被忽视的案例。 

考虑`a = 1, b = 1`。 答案是`2`。 增加腿的长度是有害的，因为任何更大的跳跃都会立即超出目标。 假设腿越大越好的解决方案会错误地返回更大的值。 

考虑`a = 1, b = 6`。 最优策略使用腿长`2`。 我们用一招加腿，然后进行一横跳三纵跳，总共`5`移动。 不断增加腿长度直到将两个坐标相除的贪婪策略会错过这一点。 

考虑`a = b = 10^9`。 最佳腿长比`10^9`。 权衡是微妙的：较大的腿减少了跳跃次数，但需要更多的升级动作。 任何仅检查除数的方法`a`和`b`会失败，因为最佳腿长通常不会除掉任何一个坐标。 

## 方法

 暴力的观点是尝试每一种可能的升级和跳跃序列。 这显然是正确的，因为它探索了到达目的地的所有有效方式。 不幸的是，州的数量呈天文数字增长。 坐标大为`10^9`，使得对位置的任何搜索完全不可行。 

第一个有用的观察是跳跃的顺序并不重要。 一旦腿长达到某个值`m`，每次跳跃都有长度`m`，与方向无关。 

假设我们确定曾经达到的最大腿长度是`m`。 没有理由增加超过`m`，因为较长的腿长度只会花费额外的动作。 到达后`m`，每次水平跳跃都会贡献`m`单位朝向`a`，并且每次垂直跳跃都会贡献`m`单位朝向`b`。 

覆盖距离`a`，我们至少需要`ceil(a / m)`水平跳跃。 如果最后一次跳跃超调，那很好，因为我们可以提前停止并适当选择分配。 同样的推理给出`ceil(b / m)`垂直跳跃。 

固定成本的总成本`m`变成`(m - 1) + ceil(a / m) + ceil(b / m)`。 

现在问题简化为找到该表达式在所有正整数上的最小值`m`。 

乍一看，有无数种选择。 关键的观察是最优的`m`永远不会很大。 该表达式的行为大致类似于`m + a/m + b/m`。 

这在附近被最小化`sqrt(a + b)`。 一次`m`变得比平方根大得多，升级成本占主导地位。 

为了`a, b ≤ 10^9`，检查所有`m`最多约`50000`就足够了。 事实上，官方的解决方案使用了bound around`sqrt(10^9)`再加上一些余量。 自从`sqrt(10^9)`大致是`31623`，迭代至`100000`对于 100 个测试用例来说足够快。

 ## 算法演练

 1. 阅读`a`和`b`。 
2. 用一个非常大的值初始化答案。 
3. 枚举候选腿长`m`从`1`达到安全上限，例如`100000`。 
4. 对于每个`m`，计算升级移动次数，即`m - 1`。 
5. 计算所需的最小水平跳跃次数：`ceil(a / m) = (a + m - 1) // m`。 
6. 计算所需的最小垂直跳跃次数：`ceil(b / m) = (b + m - 1) // m`。 
7. 该腿长的总动作次数为`(m - 1) + ceil(a / m) + ceil(b / m)`。 
8. 用迄今为止看到的最小值更新答案。 
9. 检查所有候选腿长后，输出最小答案。 

### 为什么它有效

 修正任何策略并让`m`是它所达到的最大的腿长度。 

达到腿长`m`准确地要求`m - 1`升级操作。 此后的每次跳跃最多有长度`m`。 覆盖距离`a`，至少`ceil(a / m)`水平跳跃是必要的。 同样的论证至少给出`ceil(b / m)`垂直跳跃。 

这意味着每个有效的策略至少花费`(m - 1) + ceil(a / m) + ceil(b / m)`。 

反之，对于任意选择的`m`，我们可以首先精确地执行`m - 1`升级，然后进行所需次数的水平和垂直跳跃。 这实现了相同的成本。 

因此，最优解正是该表达式在所有可能的情况下的最小值`m`，算法评估每个相关的候选者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    LIMIT = 100000
    
    for _ in range(t):
        a, b = map(int, input().split())
        
        ans = 10**18
        
        for m in range(1, LIMIT + 1):
            cur = (m - 1)
            cur += (a + m - 1) // m
            cur += (b + m - 1) // m
            ans = min(ans, cur)
        
        print(ans)

solve()
```该实现直接评估每个候选腿长的成本公式。 

表达式`(a + m - 1) // m`是标准的纯整数计算方式`ceil(a / m)`。 使用浮点运算是不必要的，并且可能会在较大输入上引入精度问题。 

上限`100000`安全地位于上方`sqrt(10^9)`。 目标函数的行为类似于`m + (a+b)/m`，因此最优值必须出现在平方根区域附近。 检查至`100000`覆盖所有相关候选人，同时保持极快的速度。 

答案变量被初始化为一个非常大的整数，并在发现较小的成本时更新。

 ## 边缘情况

 ### 已到达目的地，腿长为 1

 输入：```
1
1 1
```为了`m = 1`，成本为`0 + 1 + 1 = 2`。 

任何更大的`m`至少需要花费一次升级动作并且无法改善结果。 算法正确返回`2`。 

### 一个坐标小，另一个大

 输入：```
1
1 6
```该算法评估所有候选腿长。 为了`m = 2`和`m = 3`，成本变为`5`，这是最优的。 

总是保持腿长的贪婪策略`1`会产生`7`，因此这一案例验证了即使一个坐标已经很小，升级有时也是有益的。 

### 非常大的坐标

 输入：```
1
1000000000 1000000000
```最佳的腿长是在平方根附近，而不是接近平方根`10^9`。 该算法检查所有候选者最多`100000`，包括最佳区域，并仅使用整数算术计算精确的最小值。 

这可以避免溢出并避免对浮点精度的任何依赖。
