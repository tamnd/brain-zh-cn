 ## 解决方案
 ## 问题理解

 我们得到了患者到达时间的排序列表。 每个患者都会在特定的时刻到达，并愿意等待有限的时间单位，这意味着他们有一个可以接种疫苗的窗口。 如果他们准时到达$t_i$，那么它们可以在任意整数时间提供服务$t_i$到$t_i + w$。 

疫苗不是单独的单位，而是捆绑在包装中$k$剂量。 一旦打开包装，必须在固定的使用寿命内使用：如果按时打开$x$，只能从时间开始使用$x$到$x + d$。 此后，任何剩余的剂量都将被丢弃。 每位患者只服用一剂。 

任务是选择何时打开包以及如何将患者分配到包中，以便每个患者在其个人等待窗口内和打开的包的有效期内接种疫苗，并使用尽可能少的包。 

输入大小最多允许$2 \cdot 10^5$跨测试用例的患者总数，因此任何解决方案对于每个测试用例都必须大致线性或接近线性。 重复尝试所有可能的患者分组的二次策略将超出限制，因为它需要检查许多重叠时间窗口之间的兼容性。 

当患者窗口几乎不重叠或不相交时，就会出现关键的边缘情况。 例如，如果$w = 0$，每个患者必须在到达时间准确地得到服务，因此只有在多个患者同时到达的情况下才可能进行分组。 另一个极端情况是当$d = 0$，这意味着一个包只能在确切的打开时刻使用，因此每个包最多有效服务一个时刻，无论$k$。 

## 方法

 一个天真的想法是模拟一位一位地分配患者，对于每个患者，如果现有的已打开的包仍然有效且有剩余容量，则尝试将其放入其中，否则在最佳时间打开新的包。 这需要维护所有活动包并检查每个患者的兼容性。 在最坏的情况下，许多包在时间上重叠，我们反复扫描它们以找到有效的包，从而导致$O(n^2)$行为。 

问题的结构允许更强有力的观察。 患者按顺序到达，因此我们自然会按照最早到最晚的时间对其进行处理。 每个包装一旦打开，就会定义一个固定的可用时间间隔$[x, x + d]$，并且最多可以服务$k$患者。 同时，每个患者都有自己的可用间隔$[t_i, t_i + w]$。 仅当这些间隔在服务时重叠时，包才可供患者使用。 

关键的简化是避免详细跟踪单个包，而是贪婪地决定如何对连续患者进行分组。 对于固定的起始患者，我们希望将尽可能多的后续患者打包到一个疫苗包中，同时受到两个限制：他们的服务时间必须符合共同的可行时间窗口，并且我们不得超过$k$每包患者。 

对于一组从索引开始的患者$i$，我们可以延迟打开包装的最晚时间受到该组中任何患者最早可能过期的限制，而最早可行的时间则受到该组中最迟到达时间减去等待津贴的限制。 这将分组问题变成了维持可行患者的滑动窗口，并且一旦添加另一个患者就会破坏可行性或超出容量，就会贪婪地关闭一个组。 

这将问题简化为一次通过，我们扩大患者窗口，并在约束打破时重复最终确定组。

 | --- | --- | --- | --- |
 | 简单的每包模拟 |$O(n^2)$|$O(n)$| 太慢了 |
 | 贪心滑动分组|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们按照到达时间递增的顺序处理患者，并维护代表分配到同一包的患者的当前批次。 

1. 从第一个患者开始并初始化一个空批次。 我们还保存已打开的包装数量。 
2. 对于按顺序排列的每个患者，尝试将其添加到当前批次中。 添加患者时，我们会检查该批次在时间上是否仍然可行。 该批次必须能够在尊重患者等待限制和疫苗寿命的共同时间间隔内提供。 
3. 在构建批次时，我们还确保不超过$k$患者。 如果批量大小达到$k$，我们立即完成该批次，因为无论时间可行性如何，该包都无法为更多患者提供服务。 
4. 如果添加新患者会违反可行性，这意味着没有一个时间可以为批次中当前的所有患者提供服务，我们会关闭该患者之前的批次并开始新的批次。 
5. 我们重复此过程，直到处理完所有患者。 每次关闭一批疫苗时，我们都会计算一包疫苗。 

关键的隐藏步骤是可行性检查。 对于一批患者，服务时间必须位于所有患者间隔的交集处$[t_i, t_i + w]$，即$[\max t_i, \min (t_i + w)]$。 该交集还必须与某个长度的包间隔重叠$d$，但由于我们在批次内选择最佳的开放时间，因此确保交集非空并且可以由长度覆盖的可行性降低了$d$窗户。 

保持这一点的一个实用方法是跟踪批次中当前最大到达时间和最短允许服务时间。 

### 为什么它有效

 每次我们扩展批次时，我们仅添加间隔仍与当前可行服务区域重叠的患者。 由于对患者进行了排序，因此在继续之前已经考虑了可能包含患者的任何早期分组。 一旦批次结束，后续批次就不能在不违反时间限制或容量的情况下纳入这些患者。 这确保每个批次对应于最大可行连续段，并且贪婪最大分段最小化所需包的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, d, w = map(int, input().split())
    t = list(map(int, input().split()))
    
    packs = 0
    i = 0
    
    while i < n:
        packs += 1
        
        batch_size = 0
        
        # We maintain the feasible time window of the current batch
        # For patients j in batch:
        # feasible start is max(t[j])
        # feasible end is min(t[j] + w)
        left = t[i]
        right = t[i] + w
        
        j = i
        
        while j < n:
            # check if patient j can fit in current feasibility window
            new_left = max(left, t[j])
            new_right = min(right, t[j] + w)
            
            if new_left > new_right:
                break
            
            if batch_size == k:
                break
            
            left = new_left
            right = new_right
            batch_size += 1
            j += 1
        
        i = j
    
    print(packs)

if __name__ == "__main__":
    solve()
```该代码贪婪地构建每个批次。 变量`left`和`right`维护当前组中所有患者时间窗口的交集。 当路口变空时，我们停下来开始新的一包。 这`batch_size`变量确保我们永远不会超过剂量限制$k$。 指针`i`每批次后跳转到第一个未处理的患者，保证线性进展。 

一个微妙的点是我们从未明确计算包装打开时间。 它是在可行交集内隐式选择的，因此我们只跟踪这样的时间是否存在。

 ## 边缘情况

 当$w = 0$，每个患者只能在其到达时间准确地得到服务。 该算法可以处理此问题，因为交叉间隔会压缩为每个患者的单个点，因此只有在到达匹配时合并才会成功。 例如，在`1 1 0 0`有到达者`[5]`，该批次立即形成并以一包封闭。 

什么时候$k = 1$，无论时间如何，每位患者都需要单独的包。 该算法通过以下方式强制执行此操作：`batch_size == k`，在每位患者之后强制关闭，匹配最佳行为。 

什么时候$d = 0$，包装寿命为零，这意味着包装只能在打开时使用。 可行性条件仍然有效，因为任何需要不同服务时间的组都将无法交叉，除非所有患者共享共同的可行时间，从而有效地强制非常小的批次。
