 ## 解决方案
 ## 问题理解

 每个游戏从三个数字开始，形成一个等差数列，因此状态总是可以描述为$(a, a+d, a+2d)$和$d > 0$。 玩家反复选择一个坐标并增加它，但每次移动后三元组必须保持算术级数。 顺序可以互换，但“三等分”结构必须保持有效，公差只能保持不变或增加。 

单个“系列”并不对应于一场比赛，而是对应于许多场比赛：对于固定的三重比赛$(a_i, b_i, c_i)$，我们考虑所有的值$x$在$[l_i, r_i]$，并且对于每个$x$我们使用相同的起始三元组独立玩，但上限不同$x$。 总游戏是这些独立公正游戏的不相交总和，并且玩家在任何未完成的游戏中交替移动。 谁动不了，谁就输了。 

关键的结构点是，一旦我们了解了每个游戏的 Sprague-Grundy 值或至少其获胜或失败状态，它就是有限的和确定性的。 全球获胜者是通过对所有游戏贡献进行异或来确定的。 

这些限制迫使我们远离模拟动作。 最多可以有$2 \cdot 10^5$段和端点达到$10^{18}$，因此答案必须来自于每个区间贡献的封闭形式表征$O(n)$或者$O(n \log n)$全部的。 

一种天真的方法会尝试分析每个$x$单独并模拟或重新计算游戏状态。 这是不可能的，因为所有时间间隔内的比赛总数可能高达$10^{23}$在最坏的情况下。 

第二个天真的想法是独立对待每场比赛并计算起始位置是否获胜。 即使这需要理解所有可到达的状态，如果没有结构，它仍然会太慢。 

最微妙的失败情况是当间隔边界恰好在游戏以周期性模式从失败状态切换到获胜状态的点处切割时。 例如，如果对于固定的$(a,b,c)$，结果根据奇偶性或阈值而变化$x$，然后在不知道这种交替结构的情况下独立处理每个区间会导致错误的聚合。 

## 方法

 蛮力观点是考虑具有固定的单个游戏$x$。 从$(a,b,c)$，我们反复应用保留算术级数的移动。 增加一个坐标后保持算术级数的唯一方法是三元组保持“仿射刚性”：增加一个元素会迫使其他元素重新对齐，以便保留相等的间距。 这实际上意味着每次移动都对应于改变进度，同时尊重差异的下限。 

在实践中，状态空间会折叠成少量配置，这取决于我们在达到界限之前可以“拉伸”进程的程度$x$。 关键的观察是，游戏结果仅取决于初始状态是否至少有一个有效的移动，如果是，则在到达终端配置之前存在多少层强制移动。 

如果我们仔细分析，每个游戏都简化为一个简单的奇偶结构：要么该位置是终端（没有移动），要么它只有一个强制移动链，其长度取决于在违反算术级数或超出之前我们可以增加中间或端点的次数$x$。 因为公差是非减的，所以博弈不能“循环”； 它严格地向更大规模的配置移动，直到饱和。 

因此，每场比赛贡献 0（失败位置）或 1（根据 Grundy 平价计算获胜位置），并且全局游戏变成独立 1 的异或。 唯一剩下的任务是在所有间隔内进行计数$[l_i, r_i]$, 有多少个$x$产生一个获胜的起始位置。 

结构缩减表明，对于固定$(a,b,c)$，转变点发生在$x$变得足够大以允许至少一次移动，并且超过该阈值，状态稳定为确定性模式。 这将每个段变成阈值函数上的范围计数问题。

 ## 算法演练

 我们将最初的三元组重写为$a, a+d, a+2d$。 关键问题是是否有可能在有约束力的情况下采取任何行动$x$。 

1. 检查初始状态是否已经是terminal。 仅当我们可以增加一个元素并仍然保持算术级数时，移动才存在。 发生这种情况的唯一有意义的方法是，如果我们能够向上移动进度，同时保留间距，这需要下面有足够的“空间”$x$。 
2. 确定最小值$x$至少存在一个动作。 由于任何举动都会有效地推动一个端点并迫使进展重新平衡，因此限制因素是是否$x$允许严格大于$(a, a+d, a+2d)$。 如果$x = c$，无法移动； 如果$x > c$，至少有一个扩展变得可行。 
3. 得出仓位正在亏损的结论$x = c$，并为所有人赢得胜利$x > c$。 这在区间上创建了一个简单的阶跃函数$[l_i, r_i]$。 
4. 对于每个段，计算有多少个值$x$在$[l_i, r_i]$满足$x = c_i$。 由于这是一个点，因此它对每个段最多贡献 1 个点。 
5. 对各个分段的所有贡献进行异或。 如果最终异或为0，则Feature获胜； 否则 Bug 获胜。 

该算法简化为计算每个区间是否包含单个临界值$c_i$，并相应地切换奇偶校验。 

### 为什么它有效

 不变量是，移动的唯一障碍是无法在严格的上限下维持有效的算术级数。 由于级数是刚性的，任何允许的移动要么立即违反界限，要么强制进行严格增加最大元素的均匀移动。 这消除了多步分支：从终端行为到非终端行为至多有一个有意义的转换。 因此，每个游戏相当于一个单比特游戏，其价值仅取决于是否$x$跨越阈值$c_i$。 全球游戏变成了独立单位贡献的异或。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        xor = 0
        for _ in range(n):
            a, b, c, l, r = map(int, input().split())
            if l <= c <= r:
                xor ^= 1
        out.append("Bug" if xor else "Feature")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案仅检查是否达到临界值$c_i$位于每个区间内。 这对应于检测该特定子游戏是否对整体异或贡献了获胜切换。 

唯一微妙的实现细节是，所有算术都与比较无关，因此所有内容都可以安全地适合 Python 整数。 XOR 累积是针对每个测试用例进行的，因为跨测试用例的游戏是独立的。

 ## 边缘情况

 一个关键的边缘情况是当$c_i$正好位于区间的边界上。 该条件必须包含两端。 例如，如果$l = c$，游戏还是贡献了一个切换。 该算法可以正确处理这个问题，因为它使用`l <= c <= r`而不是严格的不平等。 

另一个边缘情况是当$n = 1$。 整个游戏简化为单个布尔检查，获胜者立即确定。 由于 XOR 从 0 开始，所以实现自然地处理了这个问题。 

最后，大值高达$10^{18}$不需要特殊处理，因为仅使用比较，并且 Python 整数可以处理此问题而不会溢出。
