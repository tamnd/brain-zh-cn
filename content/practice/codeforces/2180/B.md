 ## 解决方案
 ## 问题理解

 我们得到了一个字符串序列，我们必须将它们一个一个地插入到最初为空的字符串中。 每个新字符串可以放置在当前结果的左端或右端。 在所有插入之后，我们获得一个最终字符串。 我们的任务是选择插入方向，以便最终的字符串在所有可能的选择中按字典顺序最小。 

关键的困难在于每个决策都会以全局的方式影响未来的结构。 局部看起来更好的选择可能会阻碍以后更好的排列，因为一旦将字符串放置在一侧，其内部字符相对于结构的其余部分就会变得固定。 

就字符串数量而言，约束很小，每个测​​试最多 1000 个，总长度最多 4000 个。这立即排除了任何尝试所有 2^n 方向分配的方法。 即使是2^1000也是完全不可行的。 因此，我们正在寻找一个贪婪的决策过程，其中每个字符串都按照一些局部最优规则放置一次。 

微妙的边缘情况来自相同或共享长前缀的字符串。 例如，如果我们有类似的字符串`"ab"`和`"aa"`, 放置`"ab"`左侧与右侧更改在最终字典比较中首先比较哪个字符。 简单地独立比较字符串而不考虑整个构造序列的两个方向的简单方法将会失败。 

另一个特殊情况是多个字符串以同一字符开头。 仅比较第一个字符而不考虑最终的完整连接的贪婪规则可能会导致错误的早期放置，因为决定性的比较可能发生在连接块内部更深处。 

## 方法

 一个蛮力的想法是尝试将每个字符串分配到左侧或右侧的所有可能的分配。 对于每个 2^n 配置，我们构建结果字符串并按字典顺序取最小值。 这是正确的，因为它探索了所有可能的结果，但它是 n 的指数，并且在 n = 1000 时立即失败。 

重要的观察是我们不需要构建完整的候选字符串。 在每一步中，我们只在两种可能性之间做出决定：将下一个字符串放在前面或后面。 最终的字符串是块的串联，因此两个完整结果之间的字典顺序比较取决于它们不同的第一个位置。 该位置必须完全位于其中一个区块内或区块之间的边界处。 

这将问题简化为每个字符串独立的贪婪排序决策：当考虑放置字符串时`x`，我们比较两个假设的结果：当前结果 + 最后的 x，以及前面的 x + 当前结果。 我们不需要构建两个完整的字符串，我们只需要知道哪个串联按字典顺序更小。 

关键的简化是我们可以安全地在每一步中做出贪婪的决定：在放置之间`x`在左边或右边，我们比较`x + current`相对`current + x`。 两者中较小的一个决定了此步骤的最佳放置。 

这是有效的，因为决策不依赖于未来的字符串：未来的插入只会在两侧附加更多块，但它们会对称地影响两个分支。 因此，一旦我们在步骤 i 选择较小的方向，后面的选择就无法逆转在第一个不同位置建立的字典顺序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·总长度) | O（总长度）| 太慢了 |
 | 最优贪心 | O(n·总长度) | O（总长度）| 已接受 |

 ## 算法演练

 我们维护一个当前字符串`s`，最初为空。 

1. 开始于`s = ""`。 这表示任何插入之前的空结构。 无需对第一个字符串做出决定，因为前面和后面的插入都会产生相同的结果。 
2. 对于每个下一个字符串`x`，考虑两种可能的结果：放置`x`在前面给出`x + s`，将其放在后面给出`s + x`。 
3. 按字典顺序比较这两个候选字符串。 字典顺序取决于它们不同的第一个索引，因此我们直接使用Python字符串比较来模拟比较。 
4. 如果`x + s`较小，更新`s = x + s`。 否则设置`s = s + x`。 这确保在处理每个字符串后，`s`是处理字符串前缀的最佳可实现结果。 
5. 继续，直到所有字符串都被处理并输出`s`。 

这样做的原因是，一旦我们承诺将字符串放在一侧，所有未来的字符串只会将结果扩展到两个选项之间的第一个不匹配点之外。 该不匹配点永久地决定了顺序，因此后续操作无法更改在步骤 i 建立的相对顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = input().split()

        s = ""

        for i in range(n):
            x = arr[i]

            # compare two possible placements
            if x + s < s + x:
                s = x + s
            else:
                s = s + x

        print(s)

if __name__ == "__main__":
    solve()
```实现直接遵循贪心规则。 唯一重要的部分是比较`x + s < s + x`，它在此步骤中正确地模拟了两个可能的最终状态之间的字典顺序。 

一个常见的错误是尝试仅比较第一个字符或长度。 这会失败，因为决定字符可能出现在任一字符串的深处。 Python 的字符串比较已经可以正确处理完整的词典计算，因此我们可以安全地依赖它。

 ## 边缘情况

 一种边缘情况是所有字符串都相同。 该算法总是比较`x + s`和`s + x`，它们相等，因此它始终附加到右侧。 这会产生一个简单的串联，没有歧义。 

另一种情况是一个字符串是另一个字符串的前缀。 例如，`"a"`和`"ab"`根据位置的不同，可能会导致不同的词典结果。 该算法正确地解决了这个问题，因为`"ab" + "a" = "aba"`大于`"a" + "ab" = "aab"`， 所以`"a"`被放置在第一位，保持词典编排最优性。 

最后一个微妙的情况是交替使用小字符串和大字符串。 即使局部比较表明逆转，完整的串联比较也确保只有第一个不同的字符决定放置，因此早期的决定与全局字典顺序保持一致。
