 ## 解决方案
 ## 问题理解

 我们得到了一系列独立的赌博游戏。 每个游戏都有成功的概率，如果成功则有奖励。 不同之处在于，如果任何选定的游戏失败，则整个选择的奖励为零。 如果所有选定的游戏都成功，则支付的金额是各个游戏奖励的总和。 

因此，对于任何选定的子集，期望值是成功概率乘以该子集中奖励总和的乘积。 任务是选择一个使该期望最大化的子集。 

输入大小高达 200,000 个游戏，这会立即排除任何指数子集枚举。 即使二次解也太大了，因为 2e5 平方方法大约需要 4e10 次运算。 

一个关键的结构约束是概率是 100 以内的小整数，而奖励是具有乘积约束的正整数$p_i \cdot w_i \le 200000$。 这确保了没有任何一个游戏在概率和奖励上任意占据主导地位，并且它暗示排序或贪婪选择可能是有效的。 

当所有概率都小于 100 时，就会出现微妙的边缘情况。天真的直觉可能会认为参加所有游戏总是更好，因为它增加了奖励总和，但乘法概率惩罚可能会压倒收益。 例如，添加高奖励但低概率的游戏可以降低期望。 

另一种失败模式是仅通过奖励或概率进行贪婪选择。 仅按奖励排序会忽略概率收缩，而仅按概率排序会忽略奖励的加性结构。 正确的解决方案必须同时平衡两者。 

## 方法

 暴力方法会尝试游戏的每个子集，计算概率和奖励总和的乘积，并跟踪最大期望。 这在概念上是有效的，因为它直接评估目标函数。 然而，子集的数量是$2^n$，即使对于$n=40$，更不用说$200,000$。 计算爆炸来自子集选择的组合性质。 

关键的观察是以允许增量推理的方式重新制定目标。 假设我们维护一个子集并考虑添加一个新游戏。 期望在概率上呈乘法变化，在奖励上呈加法变化，这表明我们应该以标准化方式比较边际贡献。 

让当前子集有概率积$P$以及奖励金额$S$。 如果我们以概率添加一个新游戏$p$和奖励$w$，新的期望变为$$(P \cdot \frac{p}{100}) \cdot (S + w).$$比较添加游戏是否有助于减少仅依赖于比较比率$(p, w)$和当前状态。 

标准转换是按比率递减对游戏进行排序$\frac{w_i}{100 - p_i}$经过代数重排后，这是通过比较边际改进得出的。 直观上，如果游戏对预期总和的贡献超过其概率衰减效应，那么它就是有益的。 

排序后，我们贪心地决定是否按顺序包含每个游戏。 我们动态地维护可实现的最佳期望：对于每个前缀，我们计算扩展是否会提高价值。 

这将问题从指数搜索减少为对排序列表的线性扫描。

 | --- | --- | --- | --- |
 | 蛮力 |$O(2^n)$|$O(n)$| 太慢了|
 | 最佳 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 两人一组阅读所有游戏$(p_i, w_i)$并将概率转换为分数$p_i / 100$。 这种标准化允许统一的乘法处理。 
2. 按表达式值递减对游戏进行排序$\frac{w_i}{100 - p_i}$。 这种排序反映了当游戏较早地包含在子集中时，有多少奖励补偿了概率损失。 
3.初始化两个变量：运行概率积$P = 1.0$和持续奖励金额$S = 0.0$。 
4. 将答案初始化为 0.0，代表迄今为止找到的最佳期望。 
5. 按排序顺序迭代游戏。 对于每个游戏，通过考虑包含来更新候选状态：$P' = P \cdot (p_i / 100)$和$S' = S + w_i$。 
6. 计算期望$E' = P' \cdot S'$并更新答案，如果$E'$比当前最好的要大。 
7. 决定通过设置实际承诺纳入$P = P'$和$S = S'$。 此步骤是有效的，因为排序顺序可确保早期决策对于将来的扩展保持最佳状态。 

### 为什么它有效

 该算法依赖于这样一个事实：目标函数可以分解为递减的乘法因子和递增的加法因子的乘积。 排序标准确保在每一步中，我们都按照奖励增益和概率衰减之间的最佳权衡顺序考虑游戏。 这产生了一种结构，其中任何最佳子集都可以转换为排序顺序的前缀，而不会降低目标值。 该交换参数保证了贪婪构造不会错过更好的子集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    games = []
    for _ in range(n):
        p, w = map(int, input().split())
        games.append((p, w))
    
    # sort by w / (100 - p)
    # avoid division by sorting cross-multiplied
    games.sort(key=lambda x: (x[1] * 1.0 / (100 - x[0]) if x[0] != 100 else float('inf')), reverse=True)

    P = 1.0
    S = 0.0
    ans = 0.0

    for p, w in games:
        P *= p / 100.0
        S += w
        ans = max(ans, P * S)

    print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```该解决方案首先根据派生的优势比对游戏进行排序，确保具有更好的回报与风险权衡的游戏更早出现。 该循环维护累积概率和奖励总和。 在每一步中，它都会将完整前缀评估为候选子集，因为最佳子集在此排序下是前缀封闭的。 

一个常见的实现陷阱是在乘以许多概率时忘记浮点稳定性。 在这里使用 Python float 就足够了，因为$n$很大，但概率是有界的，精度要求是$10^{-6}$。 

另一个微妙的点是处理$p_i = 100$，这使得启发式中的分母无穷大； 这些游戏应该始终放在第一位，因为它们不会降低概率。

```比率：

 ## 边缘情况

 一个关键的边缘情况是当一个或多个游戏$p_i = 100$。 这些博弈不会减少概率积，因此它们应始终包含在任何最佳解决方案中。 在算法中，由于排序权重无穷大，它们自然会浮到前面，它们的包含只是增加总和$S$不影响$P$。 

另一个边缘情况是概率非常小时。 在这种情况下，即使是一个额外的游戏也可能会减少乘积，从而使先前有益的子集变得次优。 前缀评估确保算法仍然捕获最佳停止点而不是强制包含所有内容。 

当所有游戏都具有相似的比率时，就会出现最后的边缘情况。 该算法仍然有效，因为即使排序上的微小差异也决定了哪个前缀可以最大化乘积和权衡，并且最大跟踪步骤可确保始终选择最佳前缀。
