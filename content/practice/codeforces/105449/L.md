 ## 解决方案
 ## 问题理解

 银行提供一种特殊的高息存款，只有当存款金额达到或超过阈值时才能开立`b`。 菲利普有`a`卢布可用，他的目标是最大限度地投入这笔高息存款。 

有一个复杂的情况：在开立主存款之前，菲利普可以开立任意数量的辅助存款。 每一笔辅助押金都会消耗一定的金额`x`从他现有的资金中提取，每次这样的操作都会降低所需的门槛`b`经过`2x`，但绝不会低于 100,000。 存入辅助存款的资金将被永久锁定，不能重复使用。 在执行任何此类操作序列后，只要满足最终所需的阈值条件，菲利普就可以使用剩余资金开设主要存款。 

任务是决定在辅助存款的最佳使用情况下，最终可以将多少钱存入主存款。 

输入由两个整数组成：可用资金`a`，和初始阈值`b`。 输出是主存款的最大可能值。 

约束条件很大，双方`a`和`b`最多 1e9。 这排除了任何试图列举将资金分割成辅助存款的所有可能方式的模拟。 任何试图考虑所有子集或所有可能的操作序列的解决方案都会太慢。 

一个微妙的点是辅助存款不需要大小相等或数量有限。 这会在整数分配上产生隐式连续优化问题，其中花钱会以线性方式减少需求，直到达到 100,000 饱和。 

一个常见的陷阱是假设贪婪的行为，比如“总是降低门槛，直到它变得足够小，然后用剩余的钱作为主要存款”，而不检查用于减少的钱是否仍然留下足够的资本来满足最终的要求。 

另一种失败情况出现时`b`已经接近十万了。 在这种情况下，超过某一点的任何辅助支出都不会产生减少的效果。`b`，因此进一步支出绝对是有害的。 

最后，如果`a < b`，仍然可以通过减少来开立主要存款`b`足够的。 然而，如果`a`太小而无法有意义地减少`b`以下`a`，那么没有策略有帮助。 

## 方法

 暴力解释会试图分割总金额`a`分成几个部分：一些部分用作辅助存款，其余部分保留为最终存款。 辅助分配的每个选择都定义了最终阈值`b'`，计算为`b - 2 * (sum of auxiliary x)`，削减为 100,000。 然后我们检查剩余的钱是否至少为`b'`，并最大化最终存款规模。 

这种方法在概念上是正确的，但它立即就会陷入组合爆炸。 分区方式的数量`a`在最坏的情况下，分解为多个整数分量是指数级的。 即使限制有限数量的操作也无济于事，因为`a`可达 1e9，使得状态空间探索变得不可能。 

关键的观察结果是，只有辅助存款的总金额才重要，而不是如何分配。 如果辅助支出总额为`s`，则阈值变为`max(100000, b - 2s)`，剩下的钱是`a - s`。 问题简化为选择一个整数`s`在`[0, a]`最大化最终存款`a - s`，受`a - s ≥ max(100000, b - 2s)`。 

这将问题转化为具有分段线性约束的一维优化。 该结构表明，最佳点要么出现在约束变得严格的边界处，要么出现在阈值达到 100,000 的饱和点处。 

我们考虑两种制度。 首先，当我们花费足够多的钱来减少`b`降至 100,000。 其次，当我们只部分减少`b`以便`b - 2s > 100,000`。 在第一种机制中，超出饱和点的支出只会减少最终存款，因此最好的策略是支出恰好足以达到 100,000。 在第二种制度中，我们强制剩余资金和门槛之间的平等，或者在进一步支出无益的边界上运作。 

这减少了检查从这些方程导出的少量候选值，而不是探索所有可能性。

 ## 算法演练

 1. 计算需要携带多少开支`b`降至 100,000。 这是`s0 = max(0, (b - 100000 + 1) // 2)`以整数形式表示，但更准确地说，我们考虑阈值条件`b - 2s ≤ 100000`。 超过这一点的支出不会进一步降低需求。 
2. 考虑我们的支出恰好足以达到饱和的情况：`s = min(a, ceil((b - 100000) / 2))`。 此后，所需的阈值变为 100,000。 剩下的钱是`a - s`，条件简化为检查是否`a - s ≥ 100000`。 如果是这样，存款规模为`a - s`。 
3. 考虑我们没有完全饱和阈值的情况。 在这种情况下，最终的约束是`a - s ≥ b - 2s`，这简化为`a + s ≥ b`。 重新排列给出`s ≥ b - a`。 由于支出会减少最终存款，因此我们需要最小的可行值`s`，即`max(0, b - a)`。 
4. 通过评估可行的候选方案来结合这两种制度`s`并选择产生最大的那个`a - s`在满足约束条件且不超过`a`。 

### 为什么它有效

 可行性条件定义了一个凸可行区域：`s`。 目标`a - s`严格递减`s`，因此最优解必须出现在最小可行值处`s`。 可行性边界由两个线性约束定义，`s ≥ b - a`和`s ≥ ceil((b - 100000)/2)`。 最低有效`s`因此由这些下限的最大值决定，剪裁为`[0, a]`。 任何更大的`s`只会降低目标，而不会提高可行性，因此除非受到饱和的强制，否则没有任何内部点可以是最优的，而饱和已经被约束捕获。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())

    INF = 10**30

    # Need s such that:
    # 1) a - s >= max(100000, b - 2s)

    # Case split encoded via lower bounds:

    # From a - s >= b - 2s  => s >= b - a
    s1 = max(0, b - a)

    # From a - s >= 100000  => s <= a - 100000, but only relevant if threshold saturated
    # Saturation requirement: b - 2s <= 100000 => s >= (b - 100000 + 1)//2
    if b <= 100000:
        s2 = 0
    else:
        s2 = (b - 100000 + 1) // 2

    # If we choose saturation, s must be at least s2 and at most a - 100000
    if a >= 100000:
        s_sat = s2
        if s_sat <= a - 100000:
            best_sat = a - s_sat
        else:
            best_sat = 0
    else:
        best_sat = 0

    # Non-saturated regime: s = s1 works if it doesn't violate saturation dominance
    s_non = s1
    if s_non <= a:
        remaining = a - s_non
        if remaining >= max(100000, b - 2 * s_non):
            best_non = remaining
        else:
            best_non = 0
    else:
        best_non = 0

    print(max(best_sat, best_non))

if __name__ == "__main__":
    solve()
```该代码首先区分了两种结构机制：一种是阈值一直降低到其下限，另一种则不是。 它计算每个制度所需的最低支出，并根据剩余资本检查可行性。 答案是两种情况下可实现的最大存款额。 

关键的实现细节是在计算需要多少支出来推动时仔细处理整数除法`b`降至 100,000。 相差一的错误在这里很常见，因为不等式涉及离散设置中的严格截止。

 ## 边缘情况

 当`b`正好是10万，无论辅助支出多少，门槛都不会改变。 最佳策略是避免花费任何东西并存入所有可用资金，因为任何辅助操作只会减少最终金额。 

什么时候`a`略低于`b`，该决定取决于支出是否可以减少`b`比减少可用资金的速度还要快。 约束条件`a + s ≥ b`表明任何减少的尝试`b`必须自我补偿，而在紧张的情况下这是不可能的。 

什么时候`a`非常大并且`b`略高于 100,000 时，最佳策略是花费恰好足以达到最低门槛的金额。 超过该点花费更多没有任何好处，并且会严格降低最终答案。
