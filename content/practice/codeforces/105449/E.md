 ## 解决方案
 ## 问题理解

 我们得到了一台自动售货机，里面有几个隐藏的隔间，每个隔间都装有一定数量的罐子。 按钮数量也相同，但标签丢失了，因此每个按钮都通过固定的未知排列秘密地连接到一个隔间。 

当我们按下按钮时，我们有效地与其指定的隔间进行交互：如果该隔间仍然有罐子，我们就会收到一罐，否则我们什么也得不到。 机器只告诉我们罐头是否被分配，但不告诉我们它来自哪个隔间，我们也从不观察剩余的库存水平。 

目标是设计一种自适应的按钮按下策略，至少保证`k`罐子以最糟糕的方式将按钮隐藏分配给隔间。 无论如何选择隐藏排列，我们都希望按下的最少次数始终足够。 

关键的困难在于我们是在部分信息下运作的。 我们无法直接识别隔间，但我们可以通过与按钮的重复交互来间接耗尽它们。 

这些约束表明任何解决方案都必须接近线性或`O(n log n)`每个测试用例，因为总计`n`所有测试用例最多可达`2 · 10^5`。 这排除了任何重复尝试许多自适应策略或分配分支的模拟。 

当除了一两个小隔间以外的所有隔间都很大时，就会出现微妙的边缘情况。 例如，如果`a = [1, 1, 100]`和`k = 2`，一种天真的方法可能会假设我们可以避免在清空小隔间时浪费压力，但实际上，任何完全接触隔间的策略都会在它最终耗尽时付出额外的不可避免的成本。 这种“最终失败的压力机”很容易被忽视，也是贪婪推理中错误答案的核心根源。 

## 方法

 蛮力观点是想象我们模拟每一种可能的自适应策略和每一种可能的隐藏排列。 对于每个策略，我们将探索成功和失败响应的所有结果，构建决策树。 该树中的每条路径都对应于一个可能的交互序列，我们将计算达到目标所需的最坏情况下的按下次数`k`成功的输出。 

这很快就变得不可行，因为每个压力机的分支取决于隐藏的隔间是否还有库存。 即使对于小`n`，状态空间呈指数增长，因为我们正在有效地探索在自适应查询下可能耗尽隔间的所有方式。 

关键的简化来自于观察我们实际花费了超出预期的额外压力。`k`成功的。 每一次成功的按压都恰好对应于从某个隔间取出的一个单元。 因此任何策略都必须至少`k`迫切需要成功的项目本身。 唯一的额外成本来自于显示隔室已耗尽的压力机，因为最终的“空”压力机不会生产罐头，但仍然消耗一次操作。 

一旦隔间耗尽，我们就无法从中获得更多好处，但我们仍然必须支付超出其检测耗尽能力的额外压力机费用。 因此，每个完全耗尽的隔间都会产生一个不可避免的开销。 

这将问题简化为推理在到达之前可以完全消耗多少个隔间`k`最坏情况下的总成功罐数。 对手的角色是根据我们被迫耗尽隔间的速度，以最具破坏性的顺序有效地为按钮分配容量。 

由于我们无法提前区分隔间，因此任何自适应策略的行为都相当于从未知多重集中逐渐积累罐头，其中元素之间唯一的结构差异是它们的大小。 最坏的情况发生在首先遇到小隔间时，因为它们会导致每单位贡献更频繁的耗尽事件`k`。 

这导致了确定性的重新表述：我们应该假设隔间按照大小递增的顺序被消耗，因为这最大化了我们在到达之前完全耗尽隔间的次数。`k`。

 ## 算法演练

 我们将问题转化为隔室大小数组上的确定性累积过程。 

### 步骤

 1. 对数组进行排序`a`按非递减顺序。 

这模拟了最坏的情况，其中最小的隔室首先被有效耗尽，在到达之前最大化耗尽事件的数量`k`。 
2.初始化两个变量：`sum = 0`对于收集的罐头和`used = 0`为完全耗尽的隔室数量。 
3. 从最小到最大迭代已排序的数组。 对于每个值`x`：

如果`sum + x < k`，我们拿下整个车厢。 我们增加`sum`经过`x`并增加`used`经过`1`，因为该隔室在到达目标之前已完全耗尽。 

如果`sum + x >= k`，我们只取这个隔间的一部分来准确地到达`k`罐并立即停止。 我们不会将此隔间视为已耗尽，因为我们从未观察到故障事件。 
4.答案是`k + used`。 这`k`术语计算成功的新闻报道，以及`used`计算由排气室造成的不可避免的印刷机故障。 

### 为什么它有效

 每个成功的罐子都对应于一次产生结果的按下。 没有任何策略可以减少以下成功按压的次数`k`。 唯一不明确的是按下按钮是否会产生罐子，而获得“无罐子”结果的唯一方法是按下指定隔间已空的按钮。 

这种空压只能在隔室完全耗尽时发生。 每个完全消耗的隔间都会贡献一次这样的空压机，一旦隔间的容量耗尽，没有任何策略可以避免支付这一成本。 由于对手可以迫使小隔间首先被消耗，因此在到达之前最大化耗尽的隔间的数量`k`，按升序排序可捕获最坏情况的结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        a.sort()
        
        s = 0
        used = 0
        
        for x in a:
            if s + x < k:
                s += x
                used += 1
            else:
                break
        
        print(k + used)

if __name__ == "__main__":
    solve()
```该解决方案对隔间尺寸进行排序，以便我们可以评估在到达之前会消耗多少个满隔间`k`。 该循环会累积贡献，直到达到阈值，并计算沿途使用了多少个完整段。 最终答案补充道`k`对于所有成功的抽牌，并添加耗尽的隔室数量，这对应于不可避免的失败压力机。 

关键的实施细节是一旦停止`s + x >= k`，因为最后一个隔间不一定已耗尽，并且计算它会错误地增加额外的故障。 

## 工作示例

 ### 示例 1

 考虑`a = [1, 1, 3]`,`k = 3`。 

我们排序：`[1, 1, 3]`。 

| 步骤| x| 之前总和 | | 之后求和 二手 |
 | ---| ---| ---| ---| ---|
 | 1 | 1 | 0 | 1 | 1 |
 | 2 | 1 | 1 | 2 | 2 |
 | 3 | 3 | 2 | 停止| 2 |

 我们停在最后一个元素，因为`2 + 3 >= 3`，这意味着我们只部分使用它。 

答案是`k + used = 3 + 2 = 5`。 

这表明两个小隔间在到达目标之前已完全耗尽，每个隔间都会造成额外的失败压力。 

### 示例 2

 考虑`a = [2, 2, 2, 2]`,`k = 5`。 

排序后的数组仍保留`[2, 2, 2, 2]`。 

| 步骤| x| 之前总和 | | 之后求和 二手 |
 | ---| ---| ---| ---| ---|
 | 1 | 2 | 0 | 2 | 1 |
 | 2 | 2 | 2 | 4 | 2 |
 | 3 | 2 | 4 | 6 | 停止|

 我们在第三步停止，因为我们达到了所需的`k`。 

答案是`5 + 2 = 7`。 

这证实了即使所有隔室都相等，完全耗尽的隔室数量也仅取决于在达到目标总和之前完全使用了多少隔室。

 ## 边缘情况

 当只有一个隔间时，算法正确返回`k`，因为如果我们只部分使用它，在达到目标之前不会发生耗尽事件。 排序循环立即达到停止条件并且不计为失败。 

当所有值都相等且`k`刚好高于该值的倍数，则在最后一个隔间部分使用之前，几个隔间已被完全消耗。 该算法精确计算那些完全消耗的次数，与不可避免的故障压力机相匹配。 

当数组包含许多小值和一个大值时，排序可确保在大值贡献足够到达之前，所有小隔间都被计为完全耗尽。`k`。 这符合最坏情况的对抗性排序，其中小隔间首先被排空，从而最大化开销。
