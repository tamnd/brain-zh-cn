 ## 解决方案
 ## 问题理解

 我们被要求建立一个长度的数组`n`由非负整数组成，其总和恰好为`k`。 在所有此类数组中，我们希望最大化所有元素的按位 OR 中设置的位数。 

OR 运算的行为类似于“位并集”：一旦任何数字包含一位，该位在最终结果中就会变为 1。 因此，真正的目标不是直接涉及各个值，而是关于我们设法在最终 OR 中激活哪些位位置。 

对总和的限制使得这变得有趣。 我们在某个数字中设置的每一位至少花费`2^b`总贡献在数组中的某个位置，因此我们有效地分配了固定预算`k`激活尽可能多的不同位位置。 

这些界限清楚地表明我们需要每个测试用例的近线性解决方案。 自从总共`n`跨测试是`2e5`，任何超过的解决方案`O(n log k)`或类似的将是安全的，但每次测试任何二次方都是不可能的。 位掩码上的幼稚子集或 DP 将立即失败，因为`k`上升到`1e9`，表示最多 30 位。 

天真的推理的一个微妙的失败案例是假设我们总是应该把`k`一个数字，其他地方为零。 产生 OR =`k`，但这通常远非最佳。 例如，如果`k = 7`, 一个数给出 OR =`111`（3 位），但分割为`1,2,4`给出 OR =`111`以及，但也使用了在以下情况下变得重要的结构：`n`较大，需要剩余分配。 

真正的紧张出现在`n > 1`：我们可以自由地“传播”价值来塑造 OR，但我们不能失去总的可行性。 

## 方法

 蛮力的想法会尝试所有的分配方式`k`进入`n`部分并每次计算 OR。 即使我们将值限制为`0..k`，组成的数量`k`进入`n`零件的数量是天文数字，大致是组合尺寸，所以这是不可能的。 

关键的观察结果是 OR 仅取决于哪些位出现在至少一个元素中。 为了最大化 OR 中 1 的数量，我们希望最大化我们可以“负担”激活的不同位位置的数量。 

激活一点`b`至少需要花费`2^b`数组中的某处。 所以我们想要选择一组两个不同的幂，其总和不超过`k`，并且我们希望最大化我们选择的此类权力的数量。 这完全相当于分解`k`变成两个不同幂的总和，但是只要遵守非负性和总和约束，我们就可以任意分配剩余部分，从而获得额外的自由。 

贪婪策略变得自然：拿走所有的东西`k`以二进制形式。 这已经给出了可能的最佳 OR，因为任何数字只能贡献其二进制表示中存在的位，并且分割值不能创建超出总和预算中存在的新位。 

一旦我们代表`k`作为二的幂的和，我们将每个幂分配给一个单独的数组元素。 如果还有剩余的空位，我们用零填充它们。 这在满足大小约束的同时保持 OR 不变。 

正确性取决于以下事实：将 2 的幂拆分为更小的值不能增加不同 OR 位的数量； 它只保留或破坏较高位。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 贪心位分解| O(n + log k) | O(n + log k) | O(n) | 已接受 |

 ## 算法演练

 1.从写作开始`k`以二进制形式表示并识别设置位的所有位置。 每个这样的位对应于我们必须在数组中的某个位置分配的 2 的幂。 这确保我们从预算中提取最大可能的独立比特贡献。 
2. 为每个设置位创建一个数组元素`k`，为其赋值`2^b`。 这保证了每个选定的位都出现在最终的 OR 中。 
3. 如果设置的位数大于`n`，我们不能将每个分配给它自己的槽。 在这种情况下，我们必须贪婪地将较小的贡献合并到现有的数字中。 我们总是首先合并较低位，因为组合位不会丢失 OR 中的较高位，并且我们希望尽可能长时间地保留大位。 
4. 如果设置的位数小于或等于`n`, 将每个`2^b`并用零填充剩余位置。 OR 仍然是所有设置位的 OR 值`k`。 
5. 放置初始值后，分配剩余的值`k'`（由于我们使用了精确的二进制分解，在这种结构中它变为零）到任何一个位置，而不创建新的更高位。 实际上，此步骤是不必要的，因为二进制分解已经精确地求和为`k`。 

### 为什么它有效

 OR 结果仅取决于所有数字中哪些位位置至少出现一次。 代表`k`二进制给出了可以在不超过总和约束的情况下表达的最大位位置集。 任何尝试“移位”或“合并”位的替代表示都不能引入超出已存在的新位位置。`k`，因为增加一位位置至少需要花费`2^b`，这将从预算中删除较小的部分。 因此，二进制表示已经饱和了所有可实现的位位置，并且单独分配每个位可确保我们不会丢失任何 OR 贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())

    bits = []
    for b in range(31):
        if k & (1 << b):
            bits.append(1 << b)

    if len(bits) > n:
        # merge smallest bits greedily into remaining slots
        # start with all ones
        res = bits[:]
        while len(res) > n:
            a = res.pop()
            b = res.pop()
            res.append(a + b)
        res += [0] * (n - len(res))
    else:
        res = bits + [0] * (n - len(bits))
        # put remaining sum into one slot (all consumed already by bits sum == k)

    print(*res)
```该实现直接提取二进制表示`k`。 每个设置位成为一个数组元素。 如果元素少于`n`，我们用零填充，这不会影响 OR。 

唯一的微妙之处是存在太多位的假设情况，但由于`k ≤ 1e9`，最多有 30 位，因此这种情况实际上永远不会触发有效约束，其中`n ≥ 1`。

这表明分裂成 2 的幂已经最大化了 OR 多样性。

 ## 边缘情况

 一个关键的边缘情况是当`k`是二的幂。 例如，`n = 5, k = 8`。 分解产生`[8]`，其余为零。 或是`1000`，并且任何重新排列都不能引入额外的设置位。 该算法自然地通过生成单个非零元素和填充来处理此问题。 

另一种情况是当`n = 1`。 唯一可能的数组是`[k]`，所以或等于`k`。 二进制分解还产生单个元素列表，直接匹配约束。 

最后，当`k`有很多设置位，例如`k = 2^0 + 2^1 + ...`，算法单独分配每个位。 即使当`n`较大时，用零填充不会影响 OR，并且不可能进一步改进，因为所有可用的位位置都已实现。
