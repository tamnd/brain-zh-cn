 ## 解决方案
 ## 问题理解

 我们有一棵树和一个特殊的操作。 

在一次操作中，我们选择任意两个顶点并查看它们之间的唯一路径。 该路径上的每个顶点都会合并为一个新顶点。 最初将某个外部顶点连接到路径的任何边都将重定向到这个新顶点。 

目标是重复执行此类路径压缩，直到整个树变成单个顶点。 我们必须找到最少的操作次数。 

由于图是一棵树，因此有$n-1$边和每对顶点之间的唯一路径。 所有测试用例的顶点总数最多为$10^5$，所以我们需要接近线性时间的东西。 任何重复修改树并搜索最佳路径的解决方案很快就会变得过于昂贵。 一个$O(n^2)$在最坏的情况下，这种方法已经太慢了。 

棘手的部分是理解路径压缩实际上对树的结构做了什么。 

考虑一个简单的链：```
1 - 2 - 3 - 4 - 5
```选择顶点 1 和 5 将整棵树压缩为一个顶点，因此答案为 1。 

输入：```
1
5
1 2
2 3
3 4
4 5
```输出：```
1
```仅基于顶点数量的粗心方法会忽略一个操作可以一次删除多个顶点。 

现在考虑一颗星：```
    2
    |
3 - 1 - 4
    |
    5
```有四片叶子。 压缩两个叶​​子之间的路径会移除这两个叶子和中心，但其他叶子仍保持​​连接。 答案不是1。 

输入：```
1
5
1 2
1 3
1 4
1 5
```输出：```
2
```这个例子表明叶子的数量比顶点的总数重要得多。 

另一个容易犯的错误是假设每次操作都会将叶子的数量减少恰好两个。 一条路径可以经过许多内部顶点，但只有它的端点可以是叶子。 准确理解叶子如何消失是关键的观察。 

## 方法

 蛮力的观点是认为树在每次操作后都会发生变化。 我们可以尝试每对可能的顶点，模拟压缩，递归地求解剩余的树，并取最小值。 

这在原则上是正确的，因为它探索了所有可能的操作序列。 不幸的是，即使一项手术已经$O(n^2)$选择，以及由此产生的树木数量呈爆炸式增长。 即使对于几十个顶点，这种方法也是完全不可行的。 

要找到有用的模式，请忘记单个顶点并专注于叶子。 

每棵具有多个顶点的树至少有两片叶子。 假设我们压缩一条端点为叶子的路径。 那条路上的所有树叶都消失了。 由于简单路径只能在其端点处有叶子，因此此操作从树中恰好删除了两个叶子。 

剩下的结构会发生什么？ 压缩路径变成单个顶点。 如果路径连接到树的其余部分，则该新顶点本身可能会成为叶子。 实际上，一项操作可以将两个现有叶子合并为一个“代表”。 

这开始看起来类似于反复配对叶子。 

让$L$是叶子的数量。 

一次操作最多可以减少叶子数 2。 为了消除所有叶子并以单个顶点结束，我们至少需要$$\left\lceil \frac{L}{2} \right\rceil$$运营。 

令人惊讶的是，这个下限总是可以实现的。 

在任何阶段，选择两个叶子并压缩它们之间的路径。 这样就不再考虑这两片叶子了。 重复这个过程可以使叶子不断配对，直到没有叶子为止。 如果$L$是偶数，我们需要$L/2$运营。 如果$L$配对后很奇怪$L-1$叶子，保留一个叶子等效结构并需要最后一次操作。 计数变为$(L+1)/2$。 

因此，答案仅取决于叶子的数量：$$\boxed{\left\lceil \frac{L}{2} \right\rceil}$$我们所需要的只是计算 1 度的顶点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读树。 
2. 通过处理所有边来计算每个顶点的度。 
3. 计算有多少个顶点的度数等于 1。令该值为$L$。 
4. 输出$(L + 1) // 2$。 

表达式$(L + 1) // 2$是整数形式$\lceil L/2 \rceil$。 

### 为什么它有效

 关键的属性是每个操作最多可以消除两个叶子，即所选路径的端点。 由于有$L$最初离开，任何解决方案至少需要$\lceil L/2 \rceil$运营。 

相反，在叶子对之间重复选择路径总是一次删除两个叶子。 这个过程正好达到了$\lceil L/2 \rceil$运营。 由于我们既有下界又有匹配结构，因此最小操作数恰好是$\lceil L/2 \rceil$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        n = int(input())

        deg = [0] * (n + 1)

        for _ in range(n - 1):
            u, v = map(int, input().split())
            deg[u] += 1
            deg[v] += 1

        leaves = 0
        for v in range(1, n + 1):
            if deg[v] == 1:
                leaves += 1

        answers.append(str((leaves + 1) // 2))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```实现直接遵循数学结果。 

度数数组存储有多少条边接触每个顶点。 在树中，叶子就是度数等于1的顶点。读取所有边后，我们对这些顶点进行计数。 

最终答案的计算方法为`(leaves + 1) // 2`，它对非负整数执行上限除以 2。 

一个常见的错误是试图模拟操作本身。 这些都没有必要。 一旦知道叶子数，答案就立即确定。 

另一个微妙的点是最小树大小。 什么时候`n = 2`，两个顶点都是叶子，所以`leaves = 2`并且公式正确返回 1。

 ## 边缘情况

 考虑最小的树：```
1
2
1 2
```两个顶点的度数都是 1，所以$L = 2$。 算法返回$(2+1)//2 = 1$。 压缩两个顶点之间的路径确实会在一次操作中产生单个顶点。 

考虑一条路径：```
1
5
1 2
2 3
3 4
4 5
```只有顶点 1 和 5 是叶子。 该算法发现$L = 2$并返回 1。选择从一端到另一端的路径覆盖每个顶点，因此一次操作是最优的。 

考虑一颗有五片叶子的星星：```
1
6
1 2
1 3
1 4
1 5
1 6
```叶子是 2、3、4、5 和 6，所以$L = 5$。 算法返回$(5+1)//2 = 3$。 错误的公式如`L // 2`将返回 2，这是不可能的，因为每个操作最多删除两片叶子。 天花板部门正确处理奇数叶子计数。
