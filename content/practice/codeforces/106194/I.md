 ## 解决方案
 ## 问题理解

 我们得到一个整数$m$最多$10^{12}$。 根据这个数字，我们考虑它的所有正因数，并按升序对它们进行排序。 排序后，我们查看连续的除数并计算有多少个相邻对恰好相差一个单位，这意味着除数集中它们之间没有整数。 

同样，我们正在扫描除数列表并询问除数包含连续整数的次数。 

输出就是这个计数。 

约束条件$m \le 10^{12}$立即排除任何尝试迭代所有整数的方法$m$。 完整扫描数轴是不可能的。 甚至迭代所有数字直到$10^{12}$或者进行简单的可分性检查将超出时间限制许多数量级。 

正确的解决方案必须依赖于亚线性时间内枚举除数，通常$O(\sqrt{m})$，因为除数是成对出现的。 

当出现一个微妙的极端情况时$m = 1$。 除数集只是$\{1\}$，因此根本不存在相邻对，答案为 0。另一种边缘情况是当$m$是质数，其中除数是$\{1, m\}$，同样没有给出连续的对。 

列出除数然后检查邻接性的简单方法是可以的，但是忘记消除重复平方根或错误排序或假设对内连续结构的简单除数枚举将会失败。 

## 方法

 解决该问题的一种暴力方法是测试从 1 到$m$，检查是否可除$m$，存储所有这些数字，对它们进行排序，然后计算相差一的相邻对。 

这是正确的，因为它直接遵循除数的定义。 然而，其成本主要由检查$m$候选者，每个都需要模运算。 那是$O(m)$，这在以下位置变得完全不可行$10^{12}$。 

除数的结构允许更强有力的观察。 每个除数$d$与$m/d$，因此所有除数都可以通过迭代生成$\sqrt{m}$。 这大大降低了枚举成本。 一旦我们收集了一个列表中的所有除数，其大小最多约为$2\sqrt{m}$，我们对它们进行排序，并将连续差值计数为 1。 

关键思想是邻接性纯粹是排序除数列表的属性，而不是如何生成除数的属性。 因此，我们将问题分为两个阶段：有效的除数生成，然后对排序列表进行线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(m)$|$O(\tau(m))$| 太慢了|
 | 最佳 |$O(\sqrt{m} \log \sqrt{m})$|$O(\sqrt{m})$| 已接受 |

 ## 算法演练

 我们有效地构造了除数表，然后分析了它的邻接结构。 

1. 迭代$i$从 1 到$\lfloor \sqrt{m} \rfloor$。 对于每个$i$，检查是否$i \mid m$。 这是我们唯一需要的范围，因为上面的任何除数$\sqrt{m}$下面有一个匹配的伙伴。 
2. 每当$i \mid m$， 添加$i$到除数列表。 这捕获了除数对的较小一侧。 
3.同时添加$m / i$如果与以下内容不同，则添加到列表中$i$。 这捕获了配对的较大除数，同时避免了重复$i^2 = m$。 
4. 对收集到的除数进行排序。 排序是必要的，因为成对生成不能保证顺序，而邻接是按排序顺序定义的。 
5. 遍历排序列表并统计有多少个索引$j$满足$d[j] + 1 = d[j+1]$。 

最后的计数就是答案。 

### 为什么它有效

 的每个除数$m$因为每个除数对都是在较小的端点发现的，所以在构造的列表中只出现一次$i \le \sqrt{m}$。 排序恢复除数的自然数字顺序。 由于邻接性是严格按照该顺序定义的，因此在排序后检查连续元素可以准确捕获除数集中的所有连续整数对。 不能遗漏任何对，因为除数集中的任何连续整数都必须按排序顺序彼此相邻出现。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

m = int(input().strip())

divs = []

i = 1
while i * i <= m:
    if m % i == 0:
        divs.append(i)
        if i * i != m:
            divs.append(m // i)
    i += 1

divs.sort()

ans = 0
for i in range(len(divs) - 1):
    if divs[i] + 1 == divs[i + 1]:
        ans += 1

print(ans)
```该代码首先读取整数并为除数构建一个空列表。 循环至$\sqrt{m}$确保我们只执行大约$10^6$最坏情况下的迭代，这对于$10^{12}$。 条件`i * i != m`避免重复计算完全平方数，否则会在排序后创建重复条目并破坏邻接计数。 

排序至关重要，因为除数是按混合顺序生成的：先是小因子，然后立即附加大因子。 如果没有排序，邻接检查将毫无意义。 

最后的循环是检查连续整数的单个线性扫描。 

## 工作示例

 ### 示例 1：$m = 9$除数生成为$1, 3, 9$。 排序后，列表保持不变。 

| 步骤| 除数列表 |
 | ---| ---|
 | 一代之后| [1,3,9]|
 | 排序后 | [1,3,9]|
 | 扫描结果 | 没有相邻的 +1 对 |

 每个连续对之间的差距都大于 1，因此答案为 0。 

这证实了非连续除数集即使很小且稀疏，也不会产生匹配。 

### 示例 2：$m = 6$除数是$1, 2, 3, 6$。 

| 步骤| 除数列表 |
 | ---| ---|
 | 一代之后| [1,2,3,6]|
 | 排序后 | [1,2,3,6]|
 | 扫描结果 | (1,2), (2,3) | (1,2), (2,3) |

 扫描检测到两个连续的整数对，确认除数集中的游程计数正确。 

此示例强调该方法仅计算局部邻接，而不计算集合内的所有对。

 ## 边缘情况

 对于$m = 1$，除数列表仅包含$[1]$。 该算法生成$i = 1$，加 1 一次，并避免添加重复项。 排序很简单，并且扫描循环不执行，产生 0。 

对于像这样的完美正方形$m = 36$， 什么时候$i = 6$，条件$i \cdot i = m$防止添加$m/i$再次。 这可以避免重复的条目，例如 6 的两个副本，这会在排序时错误地创建错误的邻接关系。 

对于质数，仅$i = 1$贡献、生产$[1, m]$。 扫描检查大于 1 的单个间隙，因此结果为 0。
