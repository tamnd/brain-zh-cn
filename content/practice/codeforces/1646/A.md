 ## 解决方案
 ## 问题理解

 我们给定一个长度序列$n+1$。 每个元素要么是范围内的“小”数字$[0, n-1]$，或一个特殊的大值等于$n^2$。 我们只被告知两件事：参数$n$以及序列中所有元素的总和，表示为$s$。 原始序列丢失，任务是确定有多少个位置包含该值$n^2$。 

序列的结构非常严格。 每个非特殊元素最多贡献$n-1$总和，而每个特殊元素恰好贡献$n^2$，它比其他任何东西都大得多。 这种尺度分离是使重建成为可能的关键特征。 

约束允许最多$2 \cdot 10^4$测试用例，与$n$最多$10^6$和$s$最多$10^{18}$。 这排除了任何尝试重建序列甚至推理单个元素的方法。 任何有效的解决方案都必须将每个测试用例简化为常数时间算术。 

一个天真的方法可能会尝试猜测有多少$n^2$元素存在，然后检查剩余的和是否可以用以下值填充$[0, n-1]$。 虽然逻辑上是正确的，但这种模拟是不必要的，因为该结构意味着之间的直接代数关系$s$,$n$，以及特殊元素的数量。 

出现微妙的边缘情况时$s = 0$。 在这种情况下，所有元素都必须为零，并且答案必然是零特殊元素。 另一种拐角情况是$s$非常大，几乎完全由$n^2$贡献； 在这里，余数仍然必须可以使用有界小值来实现，并且该问题保证了这种一致性。 

## 方法

 蛮力思想是假设特殊元素的数量$k$范围从$0$到$n+1$。 对于每位候选人$k$，我们尝试看看剩余的金额是否可以用以下方式解释$n+1-k$每个元素在$[0, n-1]$。 对于固定的$k$，我们减去$k \cdot n^2$从$s$，并检查余数是否位于$0$和$(n+1-k)(n-1)$。 这是可行的，因为剩余元素的最小可能贡献为零，而最大的贡献是当所有元素都为$n-1$。 

这种暴力扫描是正确的，但没有必要。 它仍然运行在$O(n)$每个测试用例，当$n$规模大，测试用例数量多。 

关键的观察是我们实际上不需要尝试所有值$k$。 约束结构强制唯一有效$k$，并且可以直接从总和中导出。 由于每种特殊元素都贡献了过量的$n^2$与任何正常值相比，我们可以将问题视为分裂$s$分成小值的基础部分和特殊值的固定贡献。 

让$k$元素数量等于$n^2$。 其余$n+1-k$元素贡献最多$n-1$每个，所以它们的最大可能总和是$(n+1-k)(n-1)$。 这意味着：$$k \cdot n^2 \le s \le k \cdot n^2 + (n+1-k)(n-1)$$我们不进行搜索，而是计算$k$通过贪婪提取：我们采取尽可能多的$n^2$尽可能从$s$，但我们必须确保剩余部分仍然可以由有界值组成。 因为$n^2$主导范围$[0, n-1]$，正确的$k$由整数除法结构决定$s$相对于$n^2$以及剩余的可行性。 

一个更简单的重新表述是观察一旦$k$固定，则余数为$r = s - k n^2$必须满足$0 \le r \le (n+1-k)(n-1)$。 唯一性保证确保恰好一个$k$满足这一点，并且可以使用围绕上限的算术推理在恒定时间内找到它。 

实际的解决方案减少为从最大可能的迭代$k$向下或直接求导$k$从界限。 自从$k \le n+1$， 但是也$k n^2 \le s$，我们立即得到$k \le s // n^2$。 从这个上限开始，向下调整至多恒定数量的检查，可以有效地得出答案。

 ## 算法演练

 我们专注于提取等于的元素数量$n^2$从总和中。 

1. 计算特殊元素的最大可能数量：$k = s // n^2$。 这是绝对上限，因为每个特殊元素都有贡献$n^2$，所以超过这个值就会超出总和。 
2. 夹钳$k$至多$n+1$，因为只有$n+1$元素总数。 
3. 检查该候选人是否$k$通过验证剩余金额是否有效$r = s - k \cdot n^2$可以使用形成$n+1-k$数字，每个在$[0, n-1]$。 这需要$r \le (n+1-k)(n-1)$。 
4. 如果条件不成立，则减少$k$直至其生效。 约束的结构保证最多需要恒定数量的调整，因为只有一个$k$满足可行性不等式。 

### 为什么它有效

 总和唯一地分解为两部分：$n^2$来自特殊元素和来自正常元素的有限贡献。 因为普通元素的上限为$n-1$，他们无法弥补高估$k$甚至一满$n^2$除非剩余容量完全允许。 这创造了严格的可行性窗口$k$，确保只有一个整数同时满足下限和上限。 该算法在单调条件下有效地搜索$k$，因此修正总是朝着唯一有效的解决方案发展。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, s = map(int, input().split())
        max_k = s // (n * n)
        max_k = min(max_k, n + 1)

        def ok(k):
            r = s - k * n * n
            if r < 0:
                return False
            return r <= (n + 1 - k) * (n - 1)

        k = max_k
        while k >= 0 and not ok(k):
            k -= 1

        print(k)

if __name__ == "__main__":
    solve()
```该代码计算了数量的初始上限$n^2$使用整数除法的元素。 这是安全的，因为任何额外的$n^2$将超过总和。 辅助函数`ok(k)`通过确保剩余金额符合非特殊元素的最大容量来检查可行性。 

向下调整循环很短，因为可行性条件是单调的$k$。 一旦我们传递了正确的值，任何进一步的减少只会增加可用容量，因此第一个有效的$k$遇到的就是答案。 

必须小心整数运算，因为$s$可以达到$10^{18}$，但 Python 可以安全地处理这个问题。

 ## 边缘情况

 零和案例如$n=7, s=0$强制每个元素为零，因为任何$n^2$捐款将立即超过总额。 该算法计算$k = 0$从分割步骤开始并通过可行性检查，因为剩余容量与全序列长度倍完全匹配$n-1$，它是非负的。 

完全饱和的情况，例如$n=2, s=12$产量$k = 3$直接来自$s // 4$。 余数变为零，在容量范围内$0$，确认所有元素都是特殊的。 向下调整循环从未触发，表明上限已经很紧。 

混合情况如$n=3, s=12$展示纠正行为。 初步估计$k = 1$是有效的，但是$k = 2$会失败，因为它留下负余数。 循环正确地稳定在第一个可行值，确保遵守唯一性约束而不会产生歧义。
