 ## 解决方案
 ## 问题理解

 我们得到一个数字，并要求将其表示为不同“构建块”的总和。 每个构建块必须是 2 的幂或阶乘值。 2 的幂呈指数增长，而阶乘增长得更快，因此与高达的范围相比，允许值的集合极其稀疏$10^{12}$。 

任务不仅是确定这种分解是否存在，而且还要最小化使用的不同块的数量。 独特性很重要，因此我们不能重复使用同一个强大的数字两次，即使它可以简化总和。 

关键的困难是两个数字系列在小范围内的值重叠，例如$1 = 1! = 2^0$，阶乘很快变大，但仍与目标范围内的 2 的幂之和相当。 自从$n \le 10^{12}$，我们不能尝试任意子集，但我们也不能在不仔细控制状态空间的情况下依赖贪心减法。 

当贪婪选择首先获取 2 的大幂，留下无法最佳分解的余数时，就会出现天真的失败情况。 例如，采摘$64$首先在$n=70$导致$6$， 但$6$本身是一个阶乘，应该直接配对，产生更小的表示形式。 

约束条件$t \le 100$允许每个测试用例独立处理，但强制任何每个测试的指数探索都受到严格限制。 由于下面的强者总数$10^{12}$很小（大约 60 的 2 的幂和 15 的阶乘），真实的结构是在一个小的固定宇宙上的组合。 

## 方法

 蛮力的想法很简单：枚举强大数字的所有子集，计算它们的总和，并跟踪等于的最小子集大小$n$。 由于候选人人数约为 75 人，这导致$2^{75}$子集，其规模非常大，即使经过修剪也无法使用。 

下一步是认识到我们实际上处理的不是任意数字，而是一个固定的小宇宙，它在测试用例中永远不会改变。 这允许预处理二的所有幂$10^{12}$，以及达到相同极限的所有阶乘。 此后，每个测试都成为恒定大小的集合上的子集选择问题。 

然而，即使是子集枚举也太大了。 关键的观察是，答案仅取决于选择子集，而不是排序或构造。 这将问题转化为小集合上的最短和表示，这自然由位掩码 DP 处理。 

我们将强大的数字分成一个列表$a_0, a_1, \dots, a_{m-1}$。 然后我们在位掩码上使用 DP，其中状态表示已使用的数字，并跟踪形成的总和。 自从$n$很大时，我们会将可实现的总和存储在由掩码或最小计数的总和键控的字典中，并积极修剪。 尺寸小$m$使这成为可能。 

竞争解决方案中使用的更干净且标准的简化是首先预先计算阶乘子集的所有总和（因为阶乘很少），然后贪婪地或通过二元分解处理两个的幂。 这是有效的，因为当且仅当二进制表示与使用的阶乘和不冲突时，二的幂可以表示任何余数。 

这引出了最终的想法：尝试阶乘的所有子集（最多 15 个），计算它们的总和，并检查余数是否可以使用与所使用的位不重叠的两个不同的幂来表示。 如果是，则答案是阶乘子集的大小加上余数中的位数。

 | ---| ---| ---| ---|

 ## 算法演练

 我们首先建立所有不超过阶乘的列表$10^{12}$。 这些数量很少，因此我们可以安全地枚举它们。 

接下来我们尝试这些阶乘的每个子集。 

1. 对于每个子集，计算其总和。 如果已经超过$n$, we discard it immediately because all numbers are positive and distinctness prevents reuse.
 2. 令剩余值为$r = n - \text{factorial\_sum}$。 如果$r < 0$，跳过这个子集。 
3. 现在我们尝试表示$r$使用两个不同的幂。 这只有在以下情况下才有可能：$r$不重复使用阶乘已经隐含的任何二的幂。 由于阶乘值是固定整数，因此它们的贡献已经在数值上得到考虑，因此我们只需检查是否$r$可以分解为不同的 2 的幂，这对于二进制表示来说总是正确的。 
4. 此配置的项数是所选阶乘的数量加上设置的位数$r$。 
5. 我们跟踪所有子集的最小值。 

答案是可实现的最小值，或者$-1$如果没有子集起作用。 

### 为什么它有效

 每个有效的分解都会自然地分为两个独立的部分：阶乘和二的幂。 阶乘是稀疏的，并且在不改变独特性约束的情况下不能通过二的幂来合并或模拟。 然而，二的幂构成了二进制表示下所有整数的完整基础，因此选择阶乘后的任何余数都具有唯一的分解。 由于我们尝试了所有阶乘子集，因此我们探索了所有结构上不同的方法来包含阶乘贡献，并且对于每种方法，我们都使用二进制表示来最佳地完成总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def popcount(x):
    return bin(x).count("1")

# precompute factorials up to 1e12
facts = []
val = 1
i = 1
while val <= 10**12:
    facts.append(val)
    i += 1
    val *= i

def solve(n):
    ans = float('inf')
    m = len(facts)

    for mask in range(1 << m):
        s = 0
        cnt = 0

        for i in range(m):
            if mask & (1 << i):
                s += facts[i]
                cnt += 1
                if s > n:
                    break

        if s > n:
            continue

        r = n - s
        total = cnt + popcount(r)
        ans = min(ans, total)

    return -1 if ans == float('inf') else ans

t = int(input())
for _ in range(t):
    n = int(input())
    print(solve(n))
```该代码首先在全局范围内构建一次阶乘，这是有效的，因为测试用例共享相同的约束。 每个测试都使用位掩码迭代阶乘的所有子集。 对于每个子集，它累积总和和计数，当总和超过时尽早修剪$n$。 

余数使用位计数来处理，这与选择 2 的不同幂完全对应。 

一个微妙的实现细节是子集循环内的提前终止。 如果没有它，不必要的积累仍然是正确的，但速度会更慢。 另一个重要的一点是阶乘的数量很少，因此位掩码迭代仍然可行。

 ## 边缘情况

 一个关键的边缘情况是当$n$本身就是一个强大的数字。 例如$n = 32$。 该算法正确找到空的阶乘子集，并观察到余数是 2 的一次幂，从而得出答案$1$。 任何强制阶乘包含的尝试只会增加计数，并且枚举保证我们仍然考虑空子集。 

另一个微妙的情况是阶乘包含看起来有益但实际上会恶化位数。 为了$n = 31$，与仅使用 2 的幂相比，选择任何阶乘都会立即降低剩余的二进制效率。 子集枚举确保我们仍然评估纯二进制分解路径，保持最优性。 

最终的结构边缘情况是多个阶乘组合产生相同的总和但计数不同。 由于该算法显式跟踪子集大小，因此当余数结构相同时，它自然会选择较少的阶乘，从而确保最小化$k$。
