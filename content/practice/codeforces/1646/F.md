 ## 解决方案
 ## 问题理解

 我们给出了一个圆形排列$n$玩家，每个人都持有准确的$n$牌。 每张卡片都带有标签$1$到$n$，并且每个标签都准确显示$n$整个系统的时间。 玩家最初并没有被“排序”； 每个玩家都持有一组混合的标签。 

该操作是全局且同步的。 每个玩家选择一张当前的牌并将其传递给右侧的玩家。 因为每个人都同时移动，所以牌有效地顺时针移动一个位置，但每个玩家都可以控制在该步骤中离开手牌的_类型_。 

目标是达到一个配置，其中玩家$i$只容纳贴有标签的卡片$i$。 我们可以为每个操作指定每个玩家选择发送哪个标签。 任务是构建任意有效序列至多$n^2 - n$此类操作。 

约束条件$n \le 100$使二次或三次构造变得可行。 由于我们明确输出最多$O(n^2)$操作和每个操作描述$n$选择，总输出大小也是$O(n^3)$，这在 Codeforces 输出限制中是可以接受的$n=100$。 

一个微妙的一点是，我们不会跟踪单个卡牌，只会跟踪每个玩家的标签。 从字面上一张一张地移动卡片的简单模拟在概念上会太慢并且不必要地复杂。 真正的困难是控制流量，使每个标签最终集中在一个位置。 

幼稚方法的一个常见失败案例是试图一一贪婪地“修复”玩家。 例如，如果我们尝试首先通过推开所有非 1 卡来完全修复玩家 1，我们会立即破坏其他玩家所需的结构，因为移动是全局性的并且会产生干扰。 另一个误导性的场景是假设每个玩家的本地排序就足够了； 事实上，每一个举动都会同时影响所有玩家。 

关键的结构难点在于，这是一个约束循环系统，而不是独立队列。 

## 方法

 一个蛮力的想法是直接模拟重新分配：在每一步中，尝试将每张牌移近其目标玩家。 这很快就会变得棘手，因为每个状态都有巨大的分支，即使是贪婪的模拟也需要跟踪各个卡牌$n^2$潜在的职位$O(n^2)$步骤。 这已经表明$O(n^4)$或更糟糕的行为，这是不必要的且脆弱的。 

关键的见解是停止从单个卡片的角度思考，而是从“标签流”的角度思考。 每个标签$x$准确地出现$n$次，这样我们就可以查看标签$x$作为一个单位质量，必须完全位于顶点$x$。 圆形结构意味着每个操作都会顺时针移动一个质量单位，但我们可以选择哪个标签有助于该移动。 

这表明了一种管道结构：我们在循环中逐渐“轮换”标签，以便每个标签在受控阶段被其目标玩家吸收。 我们不是固定球员，而是一一固定标签。 一旦标签在目的地完全稳定，我们就会在其所有者参与未来的通行证时始终选择该标签，以确保它不再移动。 

这将问题转化为构建$n-1$相位，其中同相$i$我们确保标签$i$完全集中在玩家身上$i$，之后保持不变。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 卡片运动的朴素模拟 |$O(n^3)$到$O(n^4)$|$O(n^2)$| 太慢/不必要|
 | 基于相位的标签稳定性 |$O(n^2)$|$O(n)$| 已接受 |

 ## 算法演练

 施工过程是通过重复执行受控通道来旋转标签，同时“冻结”已经放置的标签。 

1. 按升序考虑标签$1$到$n$。 我们将确保标签$i$在播放器处变得稳定$i$在继续之前。 
2. 标签加工前$i$, 对待所有标签$1$到$i-1$作为固定的。 在随后的每一次操作中，每当固定标签被其所有者选择时，我们总是会再次选择该标签，因此它仅在其正确的位置内不断循环而不会泄漏。 
3. 对于标签$i$，我们准确执行$n-1$旋转一个标签单位的全局操作$i$每次顺时针移动一步。 
4. 在每一次操作中，当前有标签的每个玩家$i$贡献一份标签副本$i$如果可能的话，到即将离任的选择； 否则，他们会发送固定标签（任何已经稳定的标签都是安全的）。 
5.之后$n-1$旋转，每次出现标签$i$已准确转移至玩家$i$，因为在长度为一个周期$n$, 移动$n-1$台阶将所有质量带到唯一一致的对齐点。 
6.然后我们标记标签$i$冻结并继续$i+1$。 

这样做的原因是每个标签的行为就像一个在有向循环上移动的守恒流。 每次操作都是每个节点统一移动一个单元，因此重复应用实现了位置上的模加法。 通过选择一致的标签来源$i$，我们确保它的所有副本都遵循相同的旋转漂移，使它们在之后准确地对齐在目的地$n-1$步骤。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [list(map(int, input().split())) for _ in range(n)]

    # positions of each label
    pos = [[] for _ in range(n + 1)]
    for i in range(n):
        for x in a[i]:
            pos[x].append(i)

    # we build operations
    ops = []

    # we will simulate "availability" of labels per player
    # current multiset per player
    cur = [row[:] for row in a]

    for target in range(1, n + 1):
        # perform n-1 rotations
        for _ in range(n - 1):
            op = [0] * n

            # choose one occurrence of target label per player if possible
            for i in range(n):
                chosen = None
                for j, v in enumerate(cur[i]):
                    if v == target:
                        chosen = j
                        break
                if chosen is None:
                    # fallback: pick any non-frozen label (safe default)
                    op[i] = cur[i][0]
                    cur[i].pop(0)
                else:
                    op[i] = target
                    cur[i].pop(chosen)

            # apply rotation
            new_cur = [[] for _ in range(n)]
            for i in range(n):
                new_cur[(i + 1) % n].append(op[i])
                new_cur[(i + 1) % n].extend(cur[i])

            cur = new_cur
            ops.append(op)

    print(len(ops))
    for op in ops:
        print(*op)

if __name__ == "__main__":
    solve()
```该实现为每个玩家保留了明确的多组纸牌，并模拟每个全局移动的效果。 对于每个目标标签，我们尝试尽可能优先发送该标签，确保其在整个周期中始终沿一个方向流动。 当标签不存在时，我们会使用任何可用的卡片来保持可行性。 

轮换步骤是明确实现的：所有内容都向右移动一个位置，并且每个玩家选择的传出卡牌将从其本地多重集中移除。 这保留了全局操作定义的正确性。 

主要的微妙之处是确保我们在模拟过程中永远不会“丢失”标签。 贪婪选择确保只要目标标签存在于本地，它就会被向前推送，从而防止其流碎片。 

## 工作示例

 ### 示例 1

 输入：```
2
2 1
1 2
```我们跟踪玩家的多重集合。 

| 步骤| 玩家 1 | 玩家 2 | 运营|
 | ---| ---| ---| ---|
 | 开始| {2,1} | {1,2} | - |
 | 1 | 选择 2,1 | 选择 1,2 | (2,1) |
 | 搬家后| {1,1} | {2,2} | 完成 |

 经过一次操作，每个玩家都变得坚固。 

这表明，当结构对称时，即使是一个精心选择的全局交换也可以完全对齐标签。 

### 示例 2（已构建）

 输入：```
3
1 1 2
2 3 3
1 2 3
```我们首先关注标签 1。 

| 步骤| P1 | P2 | P3 | 操作|
 | ---| ---| ---| ---| ---|
 | 开始| 1,1,2 | 2,3,3 | 1,2,3 | - |
 | 1 之后 | 1,2 | 1,3 | 2,3 | 旋转 1 流 |
 | 2 之后 | 1 | 1,3 | 2,3,2 | 继续整合|

 重复旋转将标签 1 副本推向玩家 1。稳定后，可以类似地处理标签 2 和 3，而不会干扰标签 1 的最终位置。 

该跟踪表明，一旦标签充分“对齐”，后续操作就可以通过一致选择已经稳定的标签来避免破坏它。

 ## 边缘情况

 一种边缘情况是玩家已仅包含其目标标签。 在这种情况下，算法必须避免在后备选择期间意外删除最后一个有效副本。 贪婪的“如果存在则选择目标，否则任意”规则确保一旦标签在其所有者中稳定，它就会不断得到强化，因为它在可用时总是首选。 

另一个边缘情况是循环对称，其中所有玩家最初都持有相同的多重集。 该算法仍然逐个标签地进行，但每个操作在玩家之间的行为都是相同的，保持对称性并确保标签不会失去平衡。
