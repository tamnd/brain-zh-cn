 ## 解决方案
 ## 问题理解

 给定一个非负整数序列，我们可以将每个元素绘制为红色、蓝色，或者不绘制。 目标是找到一种着色，使得红色数字的总和严格大于蓝色数字的总和，而红色数字的计数严格小于蓝色数字的计数。 对于每个测试用例，我们只需要判断这种颜色是否存在即可； 我们不需要自己生产着色剂。 

输入限制很重要。 每个序列可以长达 200,000，并且测试用例中所有序列长度的总和也上限为 200,000。 这立即排除了任何考虑每个数字子集的方法，因为子集的数量呈指数增长。 因此，我们的算法在每个测试用例的元素数量上必须是线性的或接近线性的。 这些值本身最大可达 10^9，但由于我们只是将它们相加，因此整数溢出在 Python 中不是问题。 

当最大的数字位于排序序列的末尾或开头时，就会出现微妙的边缘情况。 例如，如果所有元素都相等，则任何着色都不会满足条件，因为总和随计数线性增长，使得较小的红色子集不可能超过较大的蓝色子集的总和。 另一个棘手的情况是当几个非常大的数字与许多小数字组合时； 以任意顺序选择元素的天真尝试可能会错过最佳分布。 这个问题本质上要求我们优先考虑红色的“质量”（大值）和蓝色的“数量”（许多元素）。 

## 方法

 暴力方法会尝试所有可能的方法将元素分配为红色、蓝色或未绘制的。 对于红色和蓝色的每个子集，我们可以计算总和和计数并检查条件。 这种方法适用于非常小的序列，但当 n 达到 2·10^5 时，它完全不可行，因为子集的数量为 2^n。 

关键的见解是，为了最大化红色总和，同时保持较低的红色计数，我们应该选择最大的红色元素。 相反，为了最大化蓝色计数，同时保持较低的总和，我们应该选择蓝色的最小元素。 这将问题简化为对序列进行排序并检查最大和最小元素的前缀。 具体来说，我们可以将数组按升序排序，考虑对蓝色取最小的k个元素，对红色取最大的k个元素，并增加k，直到红色总和超过蓝色总和。 如果在任何时候红色计数小于蓝色计数并且红色总和大于蓝色总和，我们可以停止并声明“是”。 如果我们到达中间而不满足这一点，答案是否定的。 由于排序，这种方法每个测试用例的时间复杂度为 O(n log n)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(3^n) | O(3^n) | O(n) | 太慢了 |

 ## 算法演练

 1.读取序列并按升序排序。 排序使我们能够系统地为蓝色选择最小的元素，为红色选择最大的元素，这是满足总和和计数条件的最佳选择。 
2. 初始化两个指针：一个指针从已排序数组的开头（蓝色元素）开始，另一个指针（红色元素）从排序数组末尾开始。 
3. 初始化两个和：`sum_blue = 0`和`sum_red = 0`。 
4. 增量添加最小元素`sum_blue`和最大的元素`sum_red`在每一步中。 跟踪红色和蓝色的计数。 
5. 每次相加后，检查当前红色总和是否超过蓝色总和以及红色计数是否小于蓝色计数。 如果两个条件都成立，则打印 YES 并停止。 
6. 如果到达红色指针与蓝色指针交叉的点并且没有找到有效的颜色，则打印 NO。 

工作原理：排序可确保每个红色元素相对于蓝色元素尽可能大，从而最大化红色总和，同时最小化红色计数。 通过增量检查更大的子集，我们保证红色总和超过蓝色总和的第一个点也满足最小红色计数要求。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()
        sum_red = 0
        sum_blue = 0
        i = 0  # index for blue (smallest)
        j = n - 1  # index for red (largest)
        count_blue = 0
        count_red = 0
        possible = False
        while i < j:
            sum_blue += a[i]
            sum_red += a[j]
            count_blue += 1
            count_red += 1
            i += 1
            j -= 1
            if sum_red > sum_blue and count_red < count_blue:
                possible = True
                break
        print("YES" if possible else "NO")

solve()
```该解决方案首先读取测试用例的数量并迭代每个序列。 排序确保我们可以为红色选择最大的值，为蓝色选择最小的值。 只要我们有未分配的元素，while 循环就会继续，同时更新总和和计数。 如果我们找到有效的着色，我们就会提前停止，这样很有效。 两个指针的选择保证了红色总是具有最大的剩余值，蓝色是最小的，直接反映了问题的约束。
