 ## 解决方案
 ## 问题理解

 我们给出一个有向图，其中每条边都有单位成本，并且保证该图是强连通的。 两个工作线程从顶点 1 开始。一系列请求到达，每个请求指定必须访问的顶点才能执行修复。 

对于每个请求，都会选择两个工作人员中的一个来处理它。 该工作人员沿着图中的最短路径从当前位置移动到所请求的顶点，然后保留在该顶点以等待将来的请求。 另一名工作人员在该请求期间没有移动。 

每个工人随着时间的推移累积总行程距离。 目标不是最小化总行程，而是平衡负载：我们希望在处理所有请求后最小化 Alice 和 Bob 累积的两个总距离中较大的一个。 

重要的结构是分配是连续的并且在位置方面不可逆转：一旦分配了请求，该工作人员的位置就会永久更改为该请求的顶点。 每一步的决策都会影响未来的旅行成本，因为未来的最短路径取决于当前的位置。 

图尺寸较小，最多 80 个顶点，最多 80 个请求。 这立即排除了任何依赖于状态上的大指数分支而不进行修剪的情况，但它允许对位置对进行动态编程。 单元边的存在和强连通性确保每对顶点之间存在最短路径，因此我们可以安全地预先计算所有对的最短路径。 

天真的贪婪策略（例如始终将当前请求分配给更接近的工作线程）会失败，因为它忽略了未来的结构。 一个工人提前搬到图表中的“坏”区域可能会导致未来大量的旅行，即使立即搬家的成本很便宜。 该决定必须考虑整个序列。 

更微妙的失败来自于仅平衡头寸而没有正确跟踪累积成本。 两个相同的位置配置可能具有完全不同的剩余可行性，具体取决于每个工人已经花费了多少预算。 

## 方法

 直接的暴力想法是尝试将每个请求的所有可能分配给 Alice 或 Bob。 有 q 个请求，因此这给出了 2^q 种可能性。 对于每个任务，我们都会使用预先计算的距离矩阵来模拟运动并计算最短路径距离。 这正确地计算出答案，但可能性的数量呈指数增长并达到大约 2^80，这远远超出了任何可行的限制。 

关键的观察是，任何时候系统的状态都由三条信息完整描述：我们在请求序列中处理了多远，Alice 当前在哪里，以及 Bob 当前在哪里。 一旦这些问题得到解决，除了累积成本之外，所有未来的决策都与我们如何达到这种状态无关。 

这表明了针对位置对的动态规划公式。 然而，目标不是简单的求和，而是 max(SA, SB) 的最小可能值，这使直接最小化变得复杂，因为仅 SA 的部分最优性并不能保证最大值的最优性。 

解决方案是将最终答案视为阈值问题。 我们不是直接最小化最大负载，而是询问是否可以处理所有请求，使得两个工作线程都不会超过给定的限制 T。如果我们可以测试固定 T 的可行性，那么我们可以二分搜索最小的有效 T。

为了进行可行性检查，我们在步骤和位置对上运行 DP，存储所有可到达的配置，其中两个工作人员的累积成本都保持在 T 范围内。由于 q 和 n 很小，因此我们可以为每个 DP 单元维护一组状态。 每个状态转换的方式是将当前请求分配给 Alice 或 Bob，添加相应的最短路径成本，并丢弃超过阈值的转换。 

这将问题转化为大小为 O(q · n²) 的状态图中的分层可达性问题，每个状态的转换大小为 2。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力作业 | O(2^q · q + n^3) | O(2^q · q + n^3) | O(1) | O(1) | 太慢了 |
 | DP + 二分查找答案 | O(log V · q · n2 · n2) ≈ O(log V · q · n3) | O(n²·状态) | 已接受 |

 这里 V 是最大可能的旅行成本，上限为 80 × 80。 

## 算法演练

 ### 全对最短路径

 我们首先使用 Floyd-Warshall 计算每对顶点之间的最短路径距离。 这是必需的，因为每次转换都取决于工作人员当前位置和下一个请求顶点之间的最短距离。 

### 固定极限 T 的可行性 DP

 我们现在检查是否可以将两个工人的总行程保持在 T 范围内。 

1. 为步骤 0 初始化 DP，其中 Alice 和 Bob 都位于顶点 1，并且都花费了 0 距离。 这是唯一有效的启动配置。 
2.一一处理请求。 在步骤 i，每个 DP 状态代表 Alice 和 Bob 的一对当前位置，以及永远不会超过 T 的隐式累积成本。 
3.对于每个状态(a,b)，考虑将下一个请求顶点x分配给Alice。 Alice 从 a 移动到 x，使她的成本增加了 dist[a][x]，而 Bob 停留在 b。 如果 Alice 的新成本不超过 T，则会创建一个新状态 (x, b)。 
4. 同样，考虑将请求分配给 Bob。 鲍勃从 b 移动到 x，增加了他的成本，而爱丽丝留在 a。 如果满足成本约束，这将创建状态 (a, x)。 
5.处理完当前请求的所有状态后，丢弃所有不可达的配置并继续下一个请求层。 
6.处理完所有请求后，如果至少有一个状态保持可达，则阈值T可行。 

### 对答案进行二分搜索

 我们二分搜索从 0 到最大可能总行程范围内的最小 T。 上限可以安全地取为图中最大最短路径距离的 q 倍。 

对于每个中点 T，我们运行上述的可行性 DP。 

### 为什么它有效

 在任何时候，DP 状态都会在处理完请求的前缀后准确存储位置的可达配置，前提是两个工作线程都不会超过当前限制 T。任何有效的完整分配都会导致通过这些状态的唯一路径。 相反，DP 中的每个转换都对应于一个有效的分配决策。 由于我们在每一步探索所有可能的分配，同时尊重约束，DP 捕获了整个可行空间。 然后，二分查找找到在最终请求后该可行空间非空的最小 T。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**9

def floyd(n, dist):
    for k in range(n):
        for i in range(n):
            dik = dist[i][k]
            if dik == INF:
                continue
            di = dist[i]
            dk = dist[k]
            for j in range(n):
                nd = dik + dk[j]
                if nd < di[j]:
                    di[j] = nd

def can(n, q, req, dist, T):
    cur = set()
    cur.add((0, 0, 0, 0))  # (a, b, sa, sb)

    for x in req:
        x -= 1
        nxt = set()
        for a, b, sa, sb in cur:
            # assign to Alice
            da = dist[a][x]
            nsa = sa + da
            if nsa <= T:
                nxt.add((x, b, nsa, sb))

            # assign to Bob
            db = dist[b][x]
            nsb = sb + db
            if nsb <= T:
                nxt.add((a, x, sa, nsb))

        if not nxt:
            return False
        cur = nxt

    return True

def solve():
    n, m = map(int, input().split())
    dist = [[INF] * n for _ in range(n)]
    for i in range(n):
        dist[i][i] = 0

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        dist[u][v] = 1

    floyd(n, dist)

    q = int(input())
    req = list(map(int, input().split()))

    lo, hi = 0, 80 * 80
    ans = hi

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(n, q, req, dist, mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```Floyd-Warshall 步骤构建了一个完整的距离矩阵，因此可以在 DP 转换期间在恒定时间内查询每个移动成本。 可行性函数明确跟踪所有可到达的位置配置和累积成本，确保在给定限制下不会错过任何有效分配。 

二分搜索包装了这种可行性检查，并逐渐收紧允许的最大负载，直到找到最小的可能值。 

一个微妙的实现细节是状态存储为完整元组，包括累积的 SA 和 SB。 这已经足够了，因为我们会修剪任何超过阈值的状态，并且除了通过 T 下的可行性之外，我们永远不需要比较不同的成本分布。 

## 工作示例

 ### 示例 1

 输入：```
3 4
1 3
3 1
1 2
2 3
2
1 3
```我们首先计算最短路径。 从 1 开始，1→3 和 1→2→3 的成本分别为 1 和 2，具体取决于路径结构。 

在请求 1、顶点 1 时，两个工作线程都处于 1，因此分配给任何一个都会以零成本产生相同的状态。 

根据请求 2、顶点 3，我们进行分支。 如果 Alice 移动到 3，SA 就变成 dist(1,3)。 如果鲍勃移动，SB 变为相同的值。 两种配置在足够大的阈值下仍然可行，但较小的阈值可能会根据路径成本消除一个分支。 

DP 探索这两种可能性，并仅保留那些使累积成本保持平衡的任务。 

### 示例 2

 输入：```
5 7
2 1
1 4
3 5
1 2
3 1
5 4
4 3
4
2 4 1 5
```我们从 1 处的两个工作人员开始。2 处的第一个请求创建两个状态：一个是 Alice 转到 2，另一个是 Bob 转到 2。后续请求根据哪个工作人员在累计成本方面更接近下一个目标，逐步分割状态空间。 

DP 保留了多种配置，但许多配置在更严格的阈值下变得无效，只留下平衡分配，将长段的移动分配给两个工人。 

这表明该算法不会提前承诺单个分配路径，而是保留多种结构可能性，直到后来的约束消除它们。

 ## 边缘情况

 当顶点之间存在多个最短路径时，就会出现极端情况。 由于所有边都有单位权重，不同的路径可能会导致相同的成本但不同的中间结构； 然而，只有最终的最短距离才重要。 Floyd-Warshall 预处理确保每次转换都使用真正的最小成本，因此 DP 不依赖于路径身份。 

另一个重要的情况是当同一个请求顶点重复出现时。 在这种情况下，最佳策略通常是交替工作人员，以避免从单个位置累积较长的重复路径。 DP 自然地捕获了这一点，因为两个分配在每个步骤中都保持可用，并且可行性过滤仅保留那些遵守限制 T 的分布。 

最后一个微妙的情况是，一名工作人员被迫提前进入一个遥远的区域，如果分配给该工作人员，则稍后的请求会变得昂贵。 DP 通过维护所有可到达的位置对来避免过早提交，因此以后的决策仍然可以将未来的请求重新分配给其他工作人员，从而保留贪婪策略将失去的可行性。
