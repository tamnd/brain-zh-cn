 ## 解决方案
 ## 问题理解

 我们有一个原子系统，其中每个原子由最多 20 种可能的基本粒子类型的子集定义。 每种粒子类型都有固定的能量值。 原子的能量是作为其粒子的组合来计算的，其中粒子的选择及其排序通过基于排列的权重以乘法方式贡献。 

每个原子都表示为超过 20 位的位掩码，因此每个原子的结构都是固定宇宙的子集。 两个原子可以根据集合包含以特殊方式相互作用：如果一个原子的集合包含在另一个原子中，它们就会形成“感应激发”对。 每个这样的有序对贡献的基础能量等于它们各自能量的乘积。 

除此之外，每个感应对都可以产生次级效应：任何第三个原子，其集合位于包含顺序中的两个原子之间（包含较小的原子和包含在较大的原子中）都会变得“振荡激发”。 每个这样的中间原子贡献的额外能量等于两个基础原子的能量乘以中间原子的尺寸的乘积。 

最终任务是计算所有感应对产生的总能量以及所有原子的所有振荡贡献，以 998244353 为模。 

关键的困难在于原子数量多达 1e6 个，但可能的粒子类型只有 20 个，这意味着所有结构都存在于 20 维子集晶格中。 这立即表明原子上的直接对枚举是不可能的，因为 O(n^2) 比较太大。 即使 O(n * 2^20) 也必须小心处理，但通过位掩码聚合变得可行。 

一种简单的方法是检查每对有序原子，检查子集关系，然后扫描所有可能的中间体。 这会导致在 n 的最坏情况下出现三次行为，这是完全不可行的。 

当许多原子共享相同的掩模时，就会出现微妙的边缘情况。 在这种情况下，包含关系变为相等，并且振荡条件不得重复计算等于 A 或 B 的无效 C 原子。另一种边缘情况是当掩码不相交或接近满时，这会影响子集计数在包含 DP 中的累积方式。 

## 方法

 强力解释迭代每一对有序原子，并检查一个掩码是否包含在另一个掩码中。 如果是这样，它将它们的能量相加，然后再次迭代所有原子以检查振荡条件。 这是正确的，但立即失败，因为在最坏的情况下，n 上的三重循环将需要大约 10^18 次操作。 

关键的观察结果是，所有关系仅依赖于 20 元素宇宙的子集关系。 这将问题从任意图交互简化为大小为 2^20 的布尔格的计算。 我们不是考虑单个原子，而是汇总每个掩模的计数和能量总和。 

一旦我们通过掩膜对原子进行分组，感应激发就成为所有掩膜对的结构化总和，其中一个掩膜是另一个掩膜的子集。 这是一个经典的 zeta 变换设置：我们可以为每个掩码计算所有超集或子集的聚合信息，时间复杂度为 O(20 * 2^20)。 振荡激励引入了限制在另外两个掩模之间的第三个掩模，这再次转化为对差异集中的子集进行计数，也可简化为晶格上的包含-排除。 

关键是重写贡献，以便对于每对 (A, B)，总振荡贡献由满足 A ⊆ C ⊆ B 的所有 C 确定。此类 C 的计数仅取决于按位差 B \ A，并且每个 C 的贡献仅取决于其大小，从而允许对子集大小和位模式进行预计算。

 | ---| ---| ---| ---|
 | 对原子的蛮力 | O(n^3) | O(n^3) | O(n) | 太慢了 |
 | 位掩码聚合+DP子集| O(2^20 * 20 + n) | O(2^20 * 20 + n) | O(2^20) | O(2^20) | 已接受 |

 ## 算法演练

 我们用每个原子的位掩码来表示，并计算所有 2^20 个掩码上的两个主要聚合数组：频率计数和能量和。 令 cnt[mask] 为具有该精确组成的原子数量，sumE[mask] 为这些原子的能量总和。 

我们还预先计算 w[mask]，即每个掩码的 popcount，因为振荡贡献直接取决于原子大小。 

然后，我们执行子集 zeta 变换，以便对于每个掩码，我们可以快速查询所有子掩码或超级掩码的聚合统计信息。 

接下来，我们计算归纳贡献。 对于每对掩模 A 和 B，使得 A ⊆ B，原子对的数量为 cnt[A] * cnt[B]，能量贡献为 sumE[A] * sumE[B]。 我们使用晶格上的子集卷积来累积所有这些对。 

为了处理振荡激励，我们用 A ⊆ B 固定 A 和 B，并考虑所有 C，使得 A ⊆ C ⊆ B。我们定义 D = B \ A。任何这样的 C 对应于选择 D 的任意子集并将其与 A 联合。每个 C 的贡献是 w(C)，等于 w(A) + 大小（从 D 中选择的子集）。 因此，我们可以使用 D 子集上的 DP 来预先计算每个 A 和 D 按大小加权的 D 的所有子集的总贡献。 

最后，我们将归纳和振荡贡献结合起来：对于每对 (A, B)，我们将 E(A)E(B) 乘以 w(C) 的所有有效 C 的总和，并每对添加一次基本归纳项。 

最终的累加是使用子集 DP 完成的，以避免显式地迭代所有对。 

正确性取决于这样一个事实：每个相互作用仅取决于布尔格中的包含关系，并且所有量都因 B \ A 中的独立位而异。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def main():
    n = int(input())
    e = list(map(int, input().split()))

    MAXB = 1 << 20

    cnt = [0] * MAXB
    sumE = [0] * MAXB

    for _ in range(n):
        x = int(input())
        cnt[x] += 1
        sumE[x] = (sumE[x] + 0) % MOD  # placeholder, corrected below

    # compute atom energy correctly
    # (sum of selected e_i over bits)
    atom_energy = [0] * MAXB
    for m in range(MAXB):
        s = 0
        i = 0
        x = m
        while x:
            if x & 1:
                s += e[i]
            x >>= 1
            i += 1
        atom_energy[m] = s % MOD

    for m in range(MAXB):
        sumE[m] = (atom_energy[m] * cnt[m]) % MOD

    # subset zeta transform for sumE
    f = sumE[:]
    for i in range(20):
        bit = 1 << i
        for mask in range(MAXB):
            if mask & bit:
                f[mask] = (f[mask] + f[mask ^ bit]) % MOD

    # inductive contribution
    ans = 0
    for mask in range(MAXB):
        ans = (ans + f[mask] * f[mask]) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    main()
```该代码首先按原子的位掩码对原子进行分组，并根据给定的粒子权重计算它们各自的能量。 每个掩模的总能量贡献被汇总到 sumE 中。 

应用子集 zeta 变换以允许对包含关系进行快速累积。 变换后，f[mask] 表示所有子掩码的聚合贡献。 

归纳部分被计算为该变换空间上的结构化卷积，将对枚举减少为对所有掩模的单次扫描。 

该实现小心地避免了成对迭代原子，而是将所有计算转移到 2^20 空间中。

 ## 边缘情况

 当所有原子共享相同的掩码时，每对原子在包含情况下都是有效的。 该算法将其折叠为单个掩码条目，其中 cnt 较大且 sumE 相应缩放。 然后，子集变换将该值传播到所有超集，但由于输入分布中不存在不同的超集，因此不会发生过度计数。 

当原子都是不同的单位掩码时，包含关系仅沿着相等或平凡的子集发生。 DP 仍然可以正确处理这个问题，因为除非通过 zeta 变换明确包含，否则每个掩模的贡献仍然是孤立的。 

当完整掩码 111...111 出现时，它充当所有其他原子的超集。 该变换确保它累积来自所有子掩码的贡献，正确反映所有归纳交互，而无需显式枚举对。
