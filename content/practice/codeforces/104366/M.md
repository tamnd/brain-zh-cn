 ## 解决方案
 ## 问题理解

 我们收到了许多独立的查询。 每个查询提供一个数字$n$，对于这个值，我们首先想象来自$2$最多$n$。 对于每个整数$i$，我们定义一个值$f(i)$， 在哪里$f(i)$是其和恰好等于的素数的最小数量$i$。 计算出每个的最佳计数后$i$，我们被要求返回累计总和$f(2) + f(3) + \dots + f(n)$对于每个查询。 

这里的关键对象是$f(i)$。 我们不是将数字进行乘法分解，而是将它们加法分解为素数，并且我们希望最小化使用的素数数量。 这将问题变成了经典的“无限硬币找零”的情况，其中每个素数都是一枚硬币，并且我们希望最少数量的硬币形成总和。 

约束非常大：最多一百万个查询和值$n$高达一千万。 这立即排除了任何重新计算的方法$f(i)$每个查询单独进行或每个查询使用动态编程。 即使每个查询进行线性扫描也会太慢，因为总工作量将激增至大约$10^{13}$最坏情况下的操作。 任何可行的解决方案都必须将所有内容简化为封闭形式表达式或在整个范围内进行一次预计算。 

可能导致错误推理的一个微妙之处是假设较大的数字需要许多素数。 例如，人们可能会尝试计算：$f(6) = 3 + 3 = 2$,$f(7) = 2 + 2 + 3 = 3$,

 然后尝试对素数进行一般 DP。 这是不必要的并且会超时。 另一个陷阱是忘记了$2$是一个素数并且可以重复使用，这强烈地约束了最优分解的结构。 

## 方法

 暴力解释将此视为最短路径或背包问题。 对于每个整数$i$，我们尝试所有素数$p \le i$并计算$f(i) = \min(f(i - p) + 1)$。 这是正确的，因为它探索分解中所有可能的最后素数，并自下而上构建解决方案。 

然而，成本主要是对每个值迭代素数，直到$n$。 即使我们用筛子预先计算素数，DP 转换仍然需要大致$O(n \cdot \pi(n))$运营。 和$n = 10^7$，这远远超出了可行的限度。 

关键的观察是，最优分解的结构几乎完全崩溃，因为素数集包含$2$。 任何整数都可以仅用$2$s，除了奇偶校验约束，其中单个$3$比额外方法更有效地帮助解决奇数和$2$s。 这导致了令人惊讶的简化：所需的最佳素数数量仅取决于奇偶性，而不取决于该数的详细素数结构。 

对于甚至$n$，仅使用$2$s 给出$n/2$素数，没有其他组合可以做得更好，因为每个素数至少$2$，所以每一项最多贡献$2$每枚硬币的总效率。 对于奇数$n \ge 3$，我们用一个$3$和其余的$2$s，给予$(n-3)/2 + 1 = (n-1)/2$素数。 这两种情况巧妙地统一为$f(n) = \lfloor n/2 \rfloor$。 

一旦看到这种减少，原始任务就变成了纯粹的算术：我们只需要前缀和$\lfloor i/2 \rfloor$。

 ## 算法演练

 我们使用封闭式$f(i) = \lfloor i/2 \rfloor$，然后将查询转换为前缀和问题。 

1. 根本不预先计算任何内容，或者可选择预先计算最多的答案$n$如果我们更喜欢前缀数组，则出现在查询中。 关键思想是我们不再需要原始信息或动态规划。 
2.对于每个查询值$n$， 定义$m = \lfloor n/2 \rfloor$。 该值表示有多少个完整的整数对适合该范围，并成为整个总和的控制参数。 
3. 使用导出的闭合形式计算答案。 如果$n = 2m$, 总和$\sum_{i=2}^{n} \lfloor i/2 \rfloor$等于$m^2$。 如果$n = 2m+1$，总和等于$m(m+1)$。 这直接来自配对连续整数并对它们的贡献求和。 
4. 每次查询立即输出计算值。 

它为何有效的根源在于如何$\lfloor i/2 \rfloor$成对行为。 每对$(2k-1, 2k)$贡献$(k-1) + k = 2k-1$，形成一个干净的算术结构。 对这些贡献求和会产生一个完全平方或类似三角形数的表达式，具体取决于奇偶校验。 自从$f(i)$正是这个底表达式，没有其他素数分解可以改变结果。 

不变的是，每个整数恰好贡献了其值的一半向下舍入作为素数的最小数量，并且这种贡献与不同整数之间的任何相互作用无关。 这消除了状态之间的所有耦合，并将问题转化为直接求和恒等式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        m = n // 2
        if n % 2 == 0:
            print(m * m)
        else:
            print(m * (m + 1))

if __name__ == "__main__":
    solve()
```该实现完全依赖于派生的封闭形式，因此没有预处理或数组分配。 唯一的微妙之处是整数除法和奇偶校验的正确处理。 使用$m = n // 2$确保统一处理偶数和奇数情况，而不会在素数逻辑或 DP 状态上分支。 

偶数情况返回$m^2$，对应于对称求和对。 奇怪的情况返回$m(m+1)$，这说明了额外的不成对项贡献$m$。

 ## 边缘情况

 对于$n = 2$，我们有$m = 1$公式给出$1$，匹配只需要一个素数的事实。 该算法正确地避免了任何特殊的大小写，因为整数除法已经产生了正确的结构。 

为了$n = 3$,$m = 1$结果是$1$，对应于使用单个素数$3$。 该公式自然地表明不需要分解为两个素数。 

对于大型甚至$n$， 例如$10^7$,$m = 5 \cdot 10^6$，结果就变成了一个完全平方数。 计算保持在 Python 整数的 64 位范围限制内，因此不会发生溢出问题。 

对于大奇数$n$, 额外项$m(m+1)$正确地解释了最后一个不成对的整数贡献，并且偶数和奇数之间的过渡保持平滑，而不会在实现中出现不连续性。
