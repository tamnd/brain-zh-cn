 ## 解决方案
 ## 问题理解

 我们正在模拟居住在一条狭窄道路上的几个邻居的活动。 每个邻居都拥有一座索引从 1 到 N 的房子。随着时间的推移，我们会收到按时间顺序排列的事件日志，描述到达和离开的尝试。 

当邻居 k 到达时，他们尝试将车直接停在他们的房子 k 前面。 然而，只有当房屋 1 到 k-1 前面的所有位置都是空的时，这才有可能。 否则，他们无法到达自己的家，而是将车停在共用停车场。 

当邻居 k 决定离开时，他们的行为取决于他们的车在哪里。 如果他们的车在共享停车区，他们立即成功离开。 如果他们的汽车停在他们的房子前面，那么只有当房子 1 到 k−1 前面的路段当前没有汽车时，他们才能离开。 如果条件不成立，他们不一定会立即离开。 他们可能会被必须先出发的较早的车辆阻挡，如果这种阻挡永远不会对他们有利，他们就会留在场地内。 

最终任务是在处理所有事件后将每个邻居分类为三种状态之一：他们从未到达、他们成功离开或他们过夜。 

约束允许最多 100,000 个事件和 100,000 个邻居。 这立即排除了通过扫描每个事件的整个房屋前缀来重新计算可见性或阻塞条件的任何解决方案，因为这在最坏的情况下会导致二次行为。 

一个关键的微妙之处在于，出发不仅仅是在请求时进行一次检查。 试图离开家的邻居可能会因为之前阻塞的汽车而被推迟，这意味着系统具有跨索引的级联依赖结构。 

打破朴素模拟的一种边缘情况是假设如果前缀在该时刻是明确的，出发请求总是立即得到解决。 例如，考虑这样一种配置：位置 5 的汽车被位置 3 的汽车阻挡，而位置 3 的汽车本身又被较早的结构阻挡。 幼稚的一次性检查会错误地将 5 标记为无法离开，即使它可能在 3 最终离开后变得空闲。 

另一个边缘情况是同一邻居多次到达和离开。 正确的解决方案必须将每次到达视为重新建立状态，而不仅仅是切换标志。 

最后，仅跟踪邻居当前是否“停车”是不够的。 我们还必须确定在前缀阻塞动态下离开房屋位置是否可行，这表明我们需要一个支持有效解决最早阻塞位置的结构。 

## 方法

 暴力方法通过在需要时显式检查所有位置 1 到 k−1 是否为空来模拟每个事件。 这需要扫描大小为 O(k) 的前缀，最坏情况下 k 可以是 O(N)。 对于 M 个事件，这会导致 O(NM) 时间复杂度，这对于 10^5 约束来说太慢了。 

主要的低效率是反复重新计算前缀区间是否没有汽车。 这表明我们需要一个可以维护动态占用并有效回答前缀空查询的数据结构。 线段树或芬威克树可以跟踪前缀中是否存在任何汽车，从而将检查时间减少到对数时间。 

然而，更深入的观察会进一步简化该过程。 与阻塞相关的唯一信息是前缀中最左边的汽车是否存在。 我们不需要完整的占用历史记录，只需要前缀在给定时间是否为空。 这可以使用一组占用位置和支持最小前缀查询的结构来维护。

正确的减少方法是在房屋前面维护一组动态有序的占用停车位。 如果停车成功，到达则插入一个位置； 离开将其删除。 移动的可行性只取决于[1,k−1]中是否存在占据的位置，相当于检查最小占据位置是否< k。 这将问题转变为维护排序结构并有效地回答前缀最小查询。 

平衡 BST 或具有前缀最小跟踪的排序集允许在对数时间内进行所有操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(NM) | O(N) | 太慢了|
 | 最优（有序集/前缀最小结构）| O(M log N) | O(M log N) | O(N) | 已接受 |

 ## 算法演练

 我们将道路建模为一组占用的停车位。 每个位置对应于当前在其家门前有一辆车的邻居。 

1. 维护所有当前占用的房屋前面位置的排序结构。 这代表按前缀顺序物理阻塞道路的所有汽车。 
2. 维护一个数组或地图来跟踪每个邻居的状态：从未到达、当前在家、当前在停车或已经离开。 这是正确解释重复事件所必需的。 
3、处理“+k”事件时，首先检查区间[1,k−1]内是否存在被占用的位置。 这相当于检查占用集合中的最小元素是否小于k。 
4. 如果不存在这样的阻塞位置，我们将 k 插入占用集合中，这意味着汽车停在它的房子前面。 否则，就认为汽车去了共享停车场，所以我们单独记录为非阻塞状态。 
5. 当处理“-k”事件时，我们检查邻居当前是否在共享停车位。 如果是这样，他们会立即离开并标记为已完成。 
6. 如果邻居把车停在他们的房子前面，我们尝试将 k 从占用集合中删除，但前提是它是当前影响其前缀条件的最小阻塞元素。 如果 k 没有被任何较小的索引阻塞，则它可以离开并被删除。 
7. 如果它被较小的索引阻塞，我们还无法将其删除。 我们将其标记为等待。 
8. 处理完所有事件后，根据每个邻居是否曾经在停车场、曾经成功移走或从未到达过，对他们进行分类。 

关键的不变量是，占用的集合始终包含当前阻塞道路某些前缀的那些汽车，并且只有在不违反前缀顺序约束的情况下才允许任何出发。 最小的占据位置充当看门人的角色：较大的索引不能离开房屋位置，而较小的索引仍然阻塞道路。 这确保了所有有效的出发都按照全局一致的顺序进行处理，而不是贪婪地处理每个事件。 

由于阻塞仅取决于前缀最小值，因此任何允许出发的配置最终都必须将汽车暴露为某个时刻的最小阻塞元素。 该算法仅在结构上符合此排序约束条件时才删除汽车，从而防止过早或无效的删除。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    present = [False] * (n + 1)
    left = [False] * (n + 1)

    parked = set()
    import bisect
    arr = []

    def has_block(k):
        if not arr:
            return False
        # smallest occupied position
        return arr[0] < k

    for _ in range(m):
        op, k = input().split()
        k = int(k)

        if op == '+':
            if not has_block(k):
                # parked in front of house
                if k not in parked:
                    parked.add(k)
                    bisect.insort(arr, k)
            else:
                # goes to external parking (not tracked in occupied set)
                pass
            present[k] = True

        else:
            # departure request
            if k in parked:
                # can only leave if no blocking smaller index remains
                # if k is currently minimal, it can leave
                if arr and arr[0] == k:
                    parked.remove(k)
                    arr.pop(0)
                    left[k] = True
            else:
                # in external parking
                left[k] = True

    for i in range(1, n + 1):
        if not present[i]:
            print(-1)
        elif left[i]:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```该解决方案保留两个状态：邻居是否到达过，以及他们是否成功离开。 名单`arr`按排序顺序维护当前阻塞道路的所有车辆，因此始终可以在 O(1) 时间内访问最小的元素。 插入使用二进制插入来保留顺序，而从前面删除则模拟解决最阻塞的汽车。 

套装`parked`区分实际阻塞道路的汽车和外部停车场的汽车。 只有停放的汽车才会与前缀约束交互。 

一个微妙的实现细节是，只有当汽车当前阻塞指数最小时才允许离开房屋。 这编码了道路前方没有较小指数汽车的约束。

 ## 边缘情况

 关键的边缘情况是邻居到达但立即被较小的索引阻塞。 在这种情况下，它们不会加入活动停放组。 例如，如果 2 在 1 已经阻塞之后到达，则 2 不能影响前缀状态，直到 1 被解析。 该算法通过仅在不存在更小的阻塞位置时插入有序结构来确保这一点。 

另一种情况是同一个邻居重复到达和离开。 由于我们分别跟踪邻居是否到达以及他们是否成功离开，因此重新到达不会覆盖最终分类。 状态是跨事件累积的。 

最后的边缘情况是当邻居当前不在阻塞集中时尝试离开。 这对应于外部停车场，总是可以立即出发。 该算法显式绕过该分支中的前缀约束，即使在内部排序不适用时也能确保正确性。
