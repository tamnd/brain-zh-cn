 ## 解决方案
 ## 问题理解

 我们得到一个非负整数数组，并要求通过对所有成对和进行重复变换，对它们进行排序，并只保留最小的$n-1$总和。 应用此操作$n-1$次，直到剩下一个数字，即输出模数$10^9+7$。 从概念上讲，每次转换仅保留涉及数组中最小数字的和，因此最大元素的贡献将逐渐被消除。 

限制因素$2 \le n \le 3000$和$0 \le a_i \le 10^9$让我们考虑一下$O(n^2)$每一步的操作，因为$3000^2 = 9 \cdot 10^6$可以在 3 秒的时间内完成。 一种简单的方法，显式地重复计算所有对的总和$n-1$迭代会有$O(n^3)$复杂性，速度太慢。 

当数组包含零、重复值或极大的数字时，会出现不明显的边缘情况。 例如，使用输入$[0, 0, 5]$，第一次转换产生$[0, 5]$最终结果是$5$。 粗心的实现可能会错误地仅对前两个元素求和或假设所有总和都是不同的。 

## 方法

 蛮力方法计算所有$\binom{n}{2}$每一步对求和，对它们进行排序，并保留最小的$n-1$总和。 这在原则上是正确的，因为它完全遵循转换定义。 为了$n = 3000$，在每次迭代中计算所有对的总和大约需要$(3000^3)/6 \approx 4.5 \cdot 10^9$超过时间限制的操作。 

更快解决方案的关键在于我们只需要跟踪最小的总和$k$每一步的要素。 如果我们对初始数组进行排序，则每次迭代的最小和可以递归地表示为上一步中最小元素的和。 具体来说，排序后，第一个$n-1$总和始终包括添加到每个剩余元素的最小元素$n-1$元素。 这将问题简化为按排序顺序重复对连续元素求和，而不是显式计算所有成对总和。 

通过使用前缀和，我们可以有效地计算结果。 对初始数组进行排序后，最后的元素$n-1$变换相当于将每个元素的贡献乘以其组合权重求和。 这种方法避免了生成所有对和并且在以下方面是线性的$n^2$操作而不是$n^3$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^3) | O(n^3) | O(n^2) | O(n^2) | 太慢了 |
 | 最佳| O(n^2) | O(n^2) | O(n) | 已接受 |

 ## 算法演练

 1.读取数组$a$长度$n$并按非降序排序。 排序确保每次迭代中最小的和可以首先由最小的元素形成。 
2. 初始化工作数组$b = a$。 该数组将表示每次迭代时序列的当前状态。 
3. 重复以下操作$n-1$次。 在每一步中，计算一个新数组$c$长度$\text{len}(b) - 1$。 填充$c[i] = b[0] + b[i+1]$。 这利用了以下属性：$n-1$最小对和总是包含最小元素$b[0]$。 
4. 更换$b$和$c$。 每次变换都会将数组大小减少 1。 
5.之后$n-1$迭代，$b$包含单个元素。 输出该值的模$10^9+7$。 

为什么它有效：不变的是，在每一步中，当前数组的最小元素总是参与$n-1$最小的总和。 排序可确保较大元素的贡献不会干扰最小的总和。 通过始终将最小元素与每个剩余元素组合，我们可以在所有迭代中正确传播最小和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n = int(input())
a = list(map(int, input().split()))
a.sort()

b = a[:]
for _ in range(n-1):
    b = [(b[0] + b[i+1]) % MOD for i in range(len(b)-1)]

print(b[0])
```解决方案首先对数组进行排序。 排序至关重要，因为它保证每次迭代中最小的元素对所有最小总和有贡献。 列表推导式通过将最小元素添加到每个其他元素来生成下一次迭代的新数组。 在每次加法期间应用模数以防止整数溢出，这对于大输入很重要。 后$n-1$迭代后，数组缩减为单个数字，这就是答案。

 | ---| ---| ---|

 输出：`5`该算法可以正确处理零，因为最小和首先涉及零。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    a.sort()

    for _ in range(n-1):
        b = [(b[0] + b[i+1]) % MOD for i in range(len(b)-1)]

 ## 边缘情况

 该算法正确处理包含零的数组。 为了`[0,0,5]`，第一次迭代将最小元素 0 与其他元素相加，产生`[0,5]`。 下一次迭代产生`[5]`。 结果是正确的。 

对于最大值，例如`[10^9, 10^9, 777]`，中间和是`[10^9+777, 10^9+777]`，再一次迭代后我们得到`[2*10^9 + 1554]`。 取模$10^9+7$产量`1540`，在尊重约束的同时避免溢出。 

该方法还处理具有所有相等元素的数组。 为了`[1,1,1,1]`，每次迭代将最小元素 1 与其他元素相加，产生`[2,2,2] -> [4,4] -> [8]`。 模运算在这里很简单，但可以确认重复值得到正确处理。
