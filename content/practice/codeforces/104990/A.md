 ## 解决方案
 ## 问题理解

 我们从一套已经产生固定月租金收入的公寓开始。 每增加一套公寓的费用都是固定的，一旦购买，它立即提供与最初的公寓相同的月收入。 目标是确定拥有的公寓总数达到目标值需要多少个月。 

动态很简单：在任何时候，每月总收入都与当前拥有的公寓数量成正比。 这些收入随着时间的推移不断积累，可以用来购买更多的公寓。 一旦购买，收入从下个月开始立即增加，因为新公寓立即开始产生租金。 

输入由三个整数组成。 一是新公寓的成本，二是每间公寓的月收入，最后是公寓的目标数量。 输出是所有权达到目标所需的最少完整月数。 

约束非常小，每个值最多为 1000。这立即排除了对重度优化或高级数据结构的任何担忧。 即使每个月都需要重复检查或循环到公寓数量，也可以进行几个月的直接模拟。 

微妙的边缘情况是收入低于单间公寓的成本。 在这种情况下，增长极其缓慢，因为每套公寓的购买可能需要几个月的时间。 例如，如果成本为10，收入为1，目标为2，则第一次购买需要10个月。 之后收入增加，所以第二次购买又需要5个月，总共15个月。 一个天真的错误是假设由于收入线性增加，因此该过程的行为就像总成本除以收入的简单划分，忽略了再投资的复利。 

当收入已经足以在一个月内购买多套公寓时，就会出现另一种边缘情况。 例如，如果成本为 5，收入为 10，那么每个月您可以立即购买两套公寓，这可能会导致快速跳跃，每个公寓的增量模拟必须仔细处理。 

## 方法

 暴力方法逐月模拟时间。 在每一步中，我们都会计算有多少钱可用，然后在我们负担得起的情况下反复购买公寓。 这是正确的，因为每个决定都是本地的：我们总是希望立即购买尽可能多的公寓，以最大化未来的收入。 然而，这种方法可能仍会逐月迭代，直到我们达到目标公寓数量。 

在最坏的情况下，假设收入很小而成本很大。 那么每次购买公寓可能需要很多个月的积累，我们可能会模拟最多C次购买，每次购买最多需要A/B个月的等待。 由于所有值都以 1000 为界，因此这仍然足够小，但我们可以通过将模拟压缩为算术步骤来做得更好。 

关键的观察是我们实际上不需要每个月都进行模拟。 重要的是我们每个点可以购买多少套公寓，以及需要多少个月才能达到下一个购买门槛。 我们可以直接计算下次购买之前的等待时间，而不是连续跟踪资金。 

在任何拥有 k 套公寓的州，每月收入为 k·B。 如果我们缺少至少一套公寓，我们会计算需要多少个月才能积累足够的钱，然后直接跳到那一刻，执行购买，然后重复。 这将流程转变为购买事件之间的一系列跳跃，而不是逐月模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 最坏情况 | O(C·A) O(1) | O(1) | 已接受 |
 | 基于事件的模拟| O(C)| O(1) | O(1) | 已接受 |

## 算法演练

 1.从一套公寓开始，累计时间为零。 目前的收入是由拥有的公寓数量决定的，所以最初是每月B。 这设定了进展的基线速度。 
2. 当公寓数量少于目标时，立即确定我们是否有能力购买至少一套公寓。 如果我们已经存了足够的钱，我们就跳过等待。 
3. 如果我们无力购买，请使用当前收入计算达到一套公寓成本所需的完整月数。 这是一个上限划分，因为部分月份对购买力没有贡献。 
4. 将时间提前计算出的月数并相应增加可用资金。 这种跳跃避免了模拟每个中间月份，因为在等待期间没有任何结构变化。 
5.一旦有了足够的钱，一步一步购买尽可能多的公寓。 每次购买都会减少可用资金并增加公寓数量，从而直接增加未来的收入。 
6. 重复此过程，直到公寓数量达到目标。 

关键思想是状态变化仅发生在购买事件中。 在两次购买之间，除了积累的钱之外没有任何变化，因此我们可以安全地及时跳跃。 

### 为什么它有效

 在任何时刻，系统都完全由公寓数量和累积资金来描述。 在购买之间，两种价值都会确定性地变化：金钱线性增加，公寓保持不变。 因此，购买成为可能的第一时刻是明确定义的，并且独立于任何中间决策。 因为我们总是尽快购买，所以我们从不推迟本来可以更早进行的购买，因此购买顺序是强制的和最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    A, B, C = map(int, input().split())

    months = 0
    apartments = 1
    money = 0

    while apartments < C:
        income = apartments * B

        if money < A:
            need = A - money
            # ceil division for months needed
            t = (need + income - 1) // income
            months += t
            money += t * income

        # buy as many as possible
        while money >= A and apartments < C:
            money -= A
            apartments += 1

    print(months)

if __name__ == "__main__":
    solve()
```该实施跟踪三个变量：以月为单位的时间、当前公寓数量和累积资金。 内部等待步骤使用上限除法计算下一次购买之前需要多少个月，这避免了一次一个月的时间。 

快进后，我们贪婪地一栋一栋地购买公寓，直到钱不够或达到目标。 这种订购是安全的，因为每次购买都会立即增加收入，并且不会阻止以后更便宜的机会。 

一个常见的错误是在计算等待时间时忘记包括当前累积的金额，这会高估延迟。 另一个是仅在完整循环迭代后更新收入，而不是在每次购买后立即更新收入。

 ## 边缘情况

 一个关键的边缘情况是收入已经大幅超过成本。 例如，输入`1 10 5`从收入10开始，意味着所有公寓都可以立即购买，无需等待。 该算法处理此问题是因为跳过了等待条件，并且在内循环中贪婪地应用了购买，导致零个月。 

另一个边缘情况是增长极其缓慢，例如`100 1 2`。 这里收入只有1，所以第一次购买需要100个月。 该算法使用上限除法来精确计算这一点，一次跳跃地提前时间，并避免模拟 100 次迭代。 

最后一种情况是平衡增长，即每次购买后收入显着增加，例如`5 2 3`。 第一次购买需要3个月，第二次需要1个月，因为收入翻倍。 模拟会在每次购买后正确地重新计算收入，确保准确捕获减少的等待时间。
