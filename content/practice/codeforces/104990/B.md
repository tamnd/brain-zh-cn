 ## 解决方案
 ## 问题理解

 我们收到了许多独立的查询。 每个查询都描述正整数上的一个区间，我们必须计算该区间内有多少数字具有其十进制表示形式从左到右和从右到左读取相同的属性。 

这个意义上的回文是纯粹基于数字的，因此任务不是关于可分性或算术结构，而是关于以 10 为基数表示的字符串对称性。 对于每个区间，我们实际上被要求计算两个给定边界之间有多少个这样的对称数字。 

约束是这里的真实信号。 最多可以有一万个查询，每个区间端点可以大到 10^18。 这立即排除了检查某个范围内的每个数字的可能性，因为即使是一个最坏情况的区间也可能包含 10^18 个值。 范围内的任何每个数字或每个数字的枚举都太慢。 我们需要一种方法来在预处理后以对数或恒定时间回答每个查询。 

有两种微妙的边缘情况打破了简单的方法。 第一个是反向输入范围。 粗心的实现可能会假设 L ≤ R 而不进行检查。 例如，输入“123 55”实际上意味着区间 [55, 123]，正确答案取决于正确解释边界而不是信任顺序。 

第二个问题是构造回文时的前导零对称性。 如果我们通过镜像数字生成回文，我们必须避免计算左半部分带有前导零的数字，因为这些数字对应于较短的有效整数并导致重复或无效构造。 例如，通过选择 2 位前缀构造 4 位回文必须确保第一个数字非零。 

## 方法

 直接方法很简单：迭代 [L, R] 中的每个数字，通过反转其数字来检查它是否是回文，并计算匹配的数字。 这是正确的，因为回文检查每个数字的时间复杂度为 O(d)，其中 d ≤ 18，因此每个查询与区间大小呈线性关系。 

问题在于规模。 在最坏的情况下，单个查询可能跨越几乎 10^18 个数字，甚至使一个查询都不可行，而对于 10^4 个查询，这种情况是完全不可能的。 

关键的观察结果是回文是稀疏且结构化的。 我们可以计算给定边界 X 之前存在的回文数，而不是单独检查数字。一旦我们可以计算函数 f(X) = 回文数 ≤ X，每个查询就会简化为 f(R) − f(L − 1)。 该问题变成了高度结构化集合上的计数问题。 

为了计算 f(X)，我们利用回文数由其前半部分数字唯一确定的事实。 对于长度为 d 的数字，我们只需要选择前 ⌈d/2⌉ 位即可； 其余的都是通过镜像强制的。 这将搜索空间从 10^18 个数字减少到大约 10^9 个候选数字，并且通过数字长度分隔和前缀计数，我们可以使用简单的算术和前缀比较来有效地计算计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(Q·R−L+1)| O(1) | O(1) | 太慢了 |
 | 最佳 | O(Q·18) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们定义一个辅助函数 f(X) 来计算 [1, X] 中的回文数。

1. 将 X 转换为其十进制数字字符串。 设其长度为d。 这让我们可以按长度分隔回文，因为所有数字较少的回文都是自动有效的候选者。 
2. 对于所有严格小于 d 的长度，计算存在多少个回文。 对于固定长度 k，回文由其前半部分确定。 如果 h = (k + 1) // 2，则第一个数字有 9 个选择（1 到 9），其余 h − 1 个数字各有 10 个选择。 所以有 9 × 10^(h − 1) 个长度为 k 的回文。 对 k < d 求和得出较短回文的总贡献。 
3. 现在处理长度恰好为 d 的回文。 我们再次考虑 X 的前半部分。设 h = (d + 1) // 2，并提取由 X 的前 h 个数字组成的前缀 P。任何有效的回文都是通过选择长度为 h 的前缀 Q 来定义的，其中 Q ≥ 10^(h−1) 以避免前导零，并对其进行镜像。 我们想要计算有多少个这样的 Q 产生回文≤ X。 
4. 我们计算所有严格小于 P 的有效 Q。如果将其解释为整数范围，则这只是 (P − 10^(h−1))。 这些对应于保证小于 X 的回文。 
5、最后检查P本身镜像形成的回文是否≤X，如果是，则再加1。 
6. 对每个查询计算所有贡献并返回 f(R) − f(L − 1)，注意 L = 1。 

它之所以有效，是基于固定长度的回文与其前半部分之间的双射。 每个有效回文都恰好对应一个有效前缀，并且这些前缀的字典顺序与长度固定时的数字顺序一致。 这确保了前缀计数正确地直接转换为回文计数，而不会遗漏或重复计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def make_pal(h, odd):
    s = str(h)
    if odd:
        return int(s + s[-2::-1])
    return int(s + s[::-1])

def count_pal(x):
    if x <= 0:
        return 0
    s = str(x)
    n = len(s)
    res = 0

    for length in range(1, n):
        half = (length + 1) // 2
        res += 9 * (10 ** (half - 1))

    half = (n + 1) // 2
    start = 10 ** (half - 1)
    prefix = int(s[:half])

    res += prefix - start

    cand = make_pal(prefix, n % 2 == 1)
    if cand <= x:
        res += 1

    return res

q = int(input())
for _ in range(q):
    l, r = map(int, input().split())
    if l > r:
        l, r = r, l
    print(count_pal(r) - count_pal(l - 1))
```核心实现分为两部分：计算较短的长度和处理边界长度。 函数 make_pal 从半前缀构造一个完整的回文，注意删除奇数长度情况下重复的中间数字。 

一个常见的实现陷阱是忘记以零开头的前缀是无效的。 这是通过使用 start = 10^(half−1) 作为最小有效前缀来处理的。 另一个微妙的问题是正确处理边界前缀的包含：我们显式地构造候选回文并将其与 x 进行比较，因为当后半部分可能使数字超出界限时，单独的前缀比较是不够的。

 ## 边缘情况

 对于反向范围（例如 L > R），算法在应用计数函数之前显式交换端点。 对于输入“123 55”，交换可确保我们评估有效区间 [55, 123]，从而防止负减法或反向减法。 

对于单位数边界，前缀逻辑永远不会遇到无效的半提取，因为低于 1 的长度被排除并直接在短长度求和循环中处理。 这保证了 X = 1 正确地产生恰好一个回文数的计数。 

对于边界前缀溢出，即前缀镜像到超过 X 的数字，显式构造和比较步骤可确保正确性。 例如，在 X = 199 时，前缀“19”将生成有效的 199，但对于 X = 191，相同的前缀将生成仍然通过的 191，而较大的隐式候选者将通过比较检查安全地排除。
