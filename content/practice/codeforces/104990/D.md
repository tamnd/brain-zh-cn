 ## 解决方案
 ## 问题理解

 我们给出了以小时和分钟表示的停车持续时间，我们首先将其转换为单个总分钟数。 停车费随着时间的推移并不恒定。 相反，时间被分为连续的段，每个段都有固定的长度和固定的每分钟价格。 我们必须模拟这些路段按顺序消耗的总停车时间，对每个路段的每一分钟收取相应的费率。 如果停车时间长于所有路段长度的总和，则剩余时间将按最后路段的费率计费。 

核心任务是计算随时间定义的分段常数函数的加权和。 

限制非常小：最多 10 层，每层长度最多 1440 分钟。 这立即意味着，即使是几分钟的简单模拟在性能方面也是微不足道的。 迭代每一层并从剩余时间中减去的解决方案就足够了，除了仔细记账之外，不需要任何高级数据结构或优化技术。 

最常见的失败案例是由于不正确的时间转换和对最后一层之外的剩余时间的不正确处理造成的。 一个典型的错误是假设各层完全覆盖停车时间并提前停车，或者忘记最后一层之外的额外时间会继续累积成本。 

例如，如果各层总共仅覆盖 100 分钟，但停车持续 150 分钟，则最后 50 分钟仍必须按最后一层的费率收费。 另一个微妙的问题是将层持续时间混淆为“绝对结束时间”而不是“间隔长度”，这会导致错误的累积索引。 

## 方法

 天真的解释是逐分钟进行模拟：将停车时长扩展为一系列分钟，并针对每一分钟确定其属于哪一层并相应地累积成本。 这是正确的，因为每一分钟都有明确定义的价格，并且所有分钟的总和与成本的定义相匹配。 

然而，如果持续时间很长，这在概念上就会变得低效，因为它需要 O(T) 操作，其中 T 是总停车时间。 在这个问题中，T 最多为 1440 分钟，因此它仍然有效，但结构建议采用更直接的累加方法。 

关键的观察是，每一层已经以恒定的速率为我们提供了一段连续的分钟。 我们可以分块消耗时间，而不是每分钟迭代：取剩余时间和当前层长度之间的最小值，乘以层速率，然后从剩余时间中减去它。 这将计算减少到层上的单次传递。 

如果处理完所有层级后还有剩余时间，我们只需对所有剩余分钟应用最后一层费率。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 逐分钟模拟 | O(T)| O(1) | O(1) | 已接受 |
 | 层块模拟| O(N) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 通过计算 T = 60·H + M 将输入时间 H 和 M 转换为总分钟数 T。这为所有进一步的计算提供了统一的单位。 
2. 按顺序阅读所有层。 每个层 i 提供持续时间 Xi 和每分钟成本 Yi，这意味着在接下来的 Xi 分钟内，每分钟成本 Yi。 
3. 初始化变量剩余 = T 和total_cost = 0。 
4. 迭代前 N−1 层。 对于每一层，计算我们实际可以使用多少分钟，即 min(remaining, Xi)。 将其乘以 Yi 并将其添加到total_cost 中。 然后从剩余金额中减去该金额。 
5. 处理完前 N−1 层后，单独处理最后一层。 如果剩余金额仍为正数，则全部按最后一级费率YN收取。 将剩余 × YN 添加到total_cost 并将剩余设置为零。 
6. 输出total_cost。 

分离最后一层的原因是，它充当超出明确定义的层结构的任何溢出时间的回退率。 

### 为什么它有效

 在每一步中，我们都会以每分钟固定的价格消耗连续块中的时间。 由于层级是按顺序定义的且没有重叠，因此每一分钟的停车时间恰好属于一个定价段。 每层的贪婪消耗确保我们将正确的速率分配给最早的未处理时间，从而保留时间的自然排序。 用尽所有定义的分段后的任何剩余时间仍必须定价，并且唯一可用的有效价格是最后一个，它充当无限延伸的终端分段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    H, M = map(int, input().split())
    N = int(input())
    
    tiers = []
    for _ in range(N):
        x, y = map(int, input().split())
        tiers.append((x, y))
    
    total = H * 60 + M
    remaining = total
    ans = 0
    
    for i in range(N - 1):
        length, cost = tiers[i]
        use = min(remaining, length)
        ans += use * cost
        remaining -= use
    
    if N > 0:
        last_length, last_cost = tiers[-1]
        ans += remaining * last_cost
    
    print(ans)

if __name__ == "__main__":
    solve()
```实现直接遵循基于块的解释。 关键的微妙之处在于使用`min(remaining, length)`以避免在中间层停车时间结束时过度消耗一层。 另一个重要的细节是我们不需要检查`remaining > 0`循环内； 乘以零自然没有任何贡献。 

最后一层是单独处理的，因此任何剩余时间，无论是否超过最后声明的持续时间，仍会一致地计费。

 ## 边缘情况

 一种重要的边缘情况是停车时间为零。 在这种情况下，总分钟数为零，循环不应产生任何成本。 该算法自然会处理这个问题，因为`remaining`从零开始，所以每个`min(remaining, Xi)`评估为零。 

另一种情况是停车时间超过所有层级边界。 假设总时间为 500 分钟，等级为 (100 at 5)、(100 at 10)、(100 at 20)。 消耗完所有层后，剩余变为 200。最后一步应用最后的费率，因此这 200 分钟按 20 计费。该算法正确地扩展了最后一层，而不需要显式的额外结构。 

最后一个微妙的情况是最后一层进入的剩余时间为零。 如果前面的层完全消耗了停车时间，`remaining`为零，乘以最后一个比率没有任何贡献。 这确保了无需特殊分支的正确性。
