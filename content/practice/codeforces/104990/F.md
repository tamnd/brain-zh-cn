 ## 解决方案
 ## 问题理解

 我们得到一棵树，它是一个没有循环的连通图，其中每条边代表一条长度相等的路径。 每个查询都会给我们三个不同的起始节点，代表三个人在这棵树中的初始位置。 

对于每个查询，我们被要求确定所需的最小可能步骤数，以便所有三个人都能到达同一节点。 每一步对应于沿着一条边移动，并且每一步中所有三个边都可以同时移动。 目标是选择一个集合点并协调行动，以便最大限度地减少三个人到达之前的总时间。 

这个措辞中隐藏的关键观察是，我们没有被要求最小化总行驶距离，而是最小化直到最后一个人到达的时间（假设平行移动）。 这将问题转化为找到一个节点，使距三个起始节点的最大距离最小。 

这些限制使得这件事变得非同小可。 该树最多有 200,000 个节点，并且可以有 100,000 个查询。 任何每次查询使用 BFS 或 DFS 重新计算距离的解决方案都会花费 O(N) 每次查询，导致 O(NQ) 远远超出可接受的限制。 如果涉及大量重新计算，即使每个查询的 O(Q log N) 预处理也会太慢。 

当三个节点已经非常接近时，例如所有节点都在同一路径上，甚至共享一个类似质心的位置，就会出现边缘情况。 在一个小示例中，例如带有查询 (1,2,3) 的链 1-2-3-4，正确答案是 1，因为节点 2 或 3 作为交汇点。 仅考虑成对距离或尝试中点平均的简单方法可能会失败，因为树距离不是欧几里德距离。 

当最佳交汇点是给定节点之一时，会出现另一种微妙的情况。 例如，如果一个节点位于另外两个节点之间的路径上，则最佳解决方案通常是在该中间节点处相遇。 假设交汇点必须是新节点或“类似中值”节点的算法可能会错过这一点。 

## 方法

 直接解决方案尝试树中每个可能的会议节点。 对于每个候选节点 x，我们使用 BFS 或 DFS 计算从 x 到 A、B 和 C 的距离，并取三者中的最大值。 然后我们选择所有 x 中的最小值。 

这是正确的，因为任何有效的会议策略都必须在某个节点结束，并且所需的时间由到达该节点最慢的人决定。 然而，重复计算每个节点的距离是非常昂贵的。 每个查询使用一个 BFS 的成本为 O(N)，而对每个候选节点执行此操作会增加另一个 N 因子，导致每个查询的成本为 O(N²)，这是不可能的。 

关键的见解是，可以使用沿树结构的距离来表达答案，而无需尝试所有节点。 在树中，任意两个节点之间的唯一路径使我们能够推断出三个点的“中心”。 一个有用的转换是修复根并使用最低公共祖先 (LCA) 查询来快速计算距离。 一旦我们能够以 O(1) 计算距离，我们就可以计算每个查询的常数公式。 

关键的恒等式是最佳会议时间等于数量的一半：

 d(A,B) + d(B,C) + d(C,A) 减去三个成对距离中的最大距离。 这是因为在树中，三个路径的并集形成一个结构，其重叠决定了可以共享多少步行。 

这将预处理后的每个查询减少为恒定时间距离计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个查询 O(N²) | O(N) | 太慢了 |
 | 最优（LCA+公式）| 每个查询 O(log N) | O(N log N) | O(N log N) | 已接受 |

 ## 算法演练

我们首先对树进行预处理，以便我们可以有效地回答任意两个节点之间的距离查询。 这是通过将树植根于任意节点并计算最低共同祖先的深度和二进制提升表来完成的。 

1. 选择任意根（通常为节点 1），然后运行 ​​DFS 来计算每个节点及其直接父节点的深度。 这为测量距离建立了参考。 
2. 构建一个二进制提升表，其中 up[v][k] 存储节点 v 的第 2^k 个祖先。这允许在对数时间内向上跳跃。 此步骤是必要的，以便可以有效地回答 LCA 查询。 
3. 定义一个函数 lca(u, v)，将较深的节点提升到与另一个节点相同的深度，然后同时提升两个节点，直到它们的祖先匹配。 交汇点是最低的共同祖先。 
4. 使用恒等式 d(u, v) = 深度[u] + 深度[v] − 2 * 深度[lca(u, v)] 定义距离函数。 这将树距离转换为算术运算。 
5. 对于每个查询（A、B、C），使用距离函数计算三个成对距离 dAB、dBC 和 dCA。 
6. 使用表达式 (dAB + dBC + dCA − max(dAB, dBC, dCA)) // 2 计算答案。这有效地删除了最长路径并正确划分剩余的重叠，以考虑向中心交汇点的共享移动。 
7. 输出该值作为所有三个节点满足所需的最短时间。 

步骤 6 背后的原因是，在树中，三个最短路径的并集形成一个结构，其中总“边使用”对共享段进行双重计数。 删除最大的成对距离可以隔离冗余重叠并产生真正的收敛时间。 

### 为什么它有效

 在树中，节点之间的路径以结构良好的方式相交，因为不存在循环。 这三个成对的路径形成一个形状为“Y”的连通子树。 最佳的交汇点位于这些分支汇合的交汇处。 该公式有效地测量了该连接点距最深分支的高度，并确保所有三个节点都能在尽可能短的同步时间内到达该连接点。 由于基于 LCA 的距离准确地捕捉了树的几何形状，因此计算值不能低估或高估真实的会议时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    LOG = (n).bit_length()
    up = [[0] * (LOG + 1) for _ in range(n + 1)]
    depth = [0] * (n + 1)

    def dfs(v, p):
        up[v][0] = p
        for to in g[v]:
            if to == p:
                continue
            depth[to] = depth[v] + 1
            dfs(to, v)

    dfs(1, 0)

    for j in range(1, LOG + 1):
        for i in range(1, n + 1):
            up[i][j] = up[up[i][j - 1]][j - 1]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a

        diff = depth[a] - depth[b]
        j = 0
        while diff:
            if diff & 1:
                a = up[a][j]
            diff >>= 1
            j += 1

        if a == b:
            return a

        for j in range(LOG, -1, -1):
            if up[a][j] != up[b][j]:
                a = up[a][j]
                b = up[b][j]

        return up[a][0]

    def dist(a, b):
        c = lca(a, b)
        return depth[a] + depth[b] - 2 * depth[c]

    q = int(input())
    out = []

    for _ in range(q):
        a, b, c = map(int, input().split())
        ab = dist(a, b)
        bc = dist(b, c)
        ca = dist(c, a)
        ans = (ab + bc + ca - max(ab, bc, ca)) // 2
        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```DFS 初始化深度和直接父关系，它们构成二进制提升的基础层。 然后向上表自下而上填充，以便任何祖先跳跃都可以分解为 2 的幂。 

LCA 函数首先通过提升更深的节点来均衡深度。 使用位分解的循环确保这在对数时间内发生。 第二阶段将两个节点一起提升，直到它们的祖先分歧。 

一旦 LCA 已知，距离计算就是基于根的深度算法的直接结果。 

每个查询仅执行恒定数量的 LCA 和距离计算，使其对于大输入大小而言足够高效。

 ## 边缘情况

 路径形树突出显示解决方案是否正确处理线性结构。 考虑 1-2-3-4 和查询 (1,4,3)。 距离为 3,1,2，得出答案 1。算法计算基于 LCA 的距离，并且算术公式正确地折叠重叠，以便节点 3 成为最佳交汇点。 

星形树检查是否正确处理通过中心节点的收敛。 对于中心 1 和叶子 2, 3, 4，查询 (2,3,4) 产生的距离全部等于 2。该公式给出 (2+2+2−2)/2 = 2，符合所有都必须经过中心的事实。 

如果一个节点位于另外两个节点之间的路径上（例如链上的 (1,2,3)），则验证中间节点是否受到适当的青睐。 LCA距离结构保证了共享段不被过度计算，因此交汇点自然地转移到中间节点，无需特殊的外壳。
