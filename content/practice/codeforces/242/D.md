 ## 解决方案
 ## 问题理解

 我们得到了一个计数器图，其中每个计数器从零开始，并通过无向电线连接。 按下计数器上的按钮，其自身的值就会增加 1，并且每个直接连接的邻居的值也会增加 1。 

我们可以选择计数器的子集，并按每个选定的计数器一次。 在所有按下之后，每个计数器都会从自身和所有选定的邻居中累积增量。 如果计数器 i 的最终值等于给定的目标值 a[i]，则该计数器被视为“匹配”。 如果任何计数器与其目标相符，瓦莱拉就输了； 只有当没有计数器最终等于其目标值时，他才会获胜。 

任务是确定是否存在要按下的顶点子集，使得没有顶点达到其目标值，如果存在，则输出任何有效子集。 

约束 n、m ≤ 100000 意味着任何解在图的大小上都必须接近线性或线性。 任何关于边或顶点的二次方都会立即变得太慢。 这也表明推理必须是局部的或每个连接组件的结构性的，因为对所有子集的全局搜索是指数级的。 

当存在孤立的顶点时，会出现微妙的边缘情况。 如果某个顶点的度数为零，则按下该顶点时，它会为自身添加 1，并且不会影响其他顶点。 如果 a[i] 等于 1，则按下该顶点会立即产生失败条件。 相反，如果 a[i] 不为 1，则根据全局一致性，它可能有用也可能没用，但它的行为是独立的。 

另一个棘手的情况出现在类似二分的传播效应中：因为每次按下都会对称地影响邻居，所以系统在组件上是线性的，因此可行性取决于约束之间的奇偶性和一致性，而不是局部贪婪的选择。 

## 方法

 一种简单的方法是尝试所有顶点子集来按下并模拟结果值。 每个子集需要 O(n + m) 来计算最终值，并且有 2^n 个子集，即使对于 n = 40，这也是完全不可行的。 

一个更结构化的观察是，按下一个顶点会为其自身和所有邻居贡献一个“1”。 这意味着每个顶点的最终值只是其封闭邻域中受压顶点的数量。 如果我们按 i 定义 x[i] 为 1，否则定义 0，那么 i 处的最终值为：

 Final[i] = x[i] + i 的所有邻居 j 的 x[j] 之和。 

这是一个整数线性系统。 我们并不是试图匹配 a[i]，而是明确地试图避免它。 所以我们需要：

 对于每个 i，x[i] + sum(x[j]) ≠ a[i]。 

我们不是直接搜索有效的 x，而是反转观点。 关键的见解是将图解释为组件并独立处理每个连接的组件。 在组件内部，约束是紧密耦合的。 这种结构使我们可以将问题简化为确定性传播：一旦我们选择是否按下单个节点，所有其他节点都将由一致性条件确定。 

考虑这个问题的一个有用方法是分配“所需的不匹配”状态。 对于每个顶点，我们定义它在所选配置下是“安全”还是“不安全”。 如果我们修复组件中的起始决策，我们可以使用从边缘导出的方程来传播强制选择。 由于每条边的贡献是对称的，因此相邻约束之间的差异会产生确定性关系。 

核心简化是，我们可以将系统视为每个连接组件上的奇偶传播问题，其中选择根值唯一地确定所有其他组件。 然后我们检查结果赋值是否避免了所有禁止的等式 a[i]。 如果是，我们接受该组件的分配； 否则，我们翻转根并重试。 如果两者都失败，则该组件是不可能的。

这是有效的，因为每个组件都会产生一个一致的线性系统，每个组件都有一个自由度，对应于我们是否按下参考顶点的选择。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集 | O(2^n · (n + m)) | O(2^n · (n + m)) | O(n + m) | 太慢了 |
 | 组件传播 | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 我们根据组件一致性重写条件，并为每个连接的组件构建一个解决方案。 

1. 为图构建邻接表并使用 DFS 或 BFS 识别所有连接的组件。 

这是必要的，因为交互不跨组件，因此每个组件都可以独立求解。 
2. 对于每个组件，选择一个任意根节点并假设暂定状态 x[root] = 0。 

这个假设只是一个起点； 该系统是线性的，因此每个组件都存在一个自由度。 
3. 遍历组件并基于受压节点的贡献总和必须在边上保持一致的约束来计算所有其他节点的隐含值。 

具体来说，我们维护一个派生关系，根据根选择来表达每个节点的状态。 
4. 传播后，计算此分配下组件中每个节点的最终结果值。 

这一步检查是否有节点满足final[i] = a[i]，这会导致损失。 
5. 如果没有节点与其禁止值匹配，则接受此分配并记录 x[i] = 1 的所有节点。 

这些正是瓦莱拉所压的柜台。 
6. 如果分配失败，则翻转根假设（x[root] = 1 而不是 0）并重复传播。 

由于每个组件只有一个二元自由度，因此这是仅有的两种可能性。 
7. 如果两个分配都导致组件中发生冲突，则得出结论：不存在有效的全局解决方案并返回 -1。 

### 为什么它有效

 每个连接的组件定义一个系统，其中每个顶点值都由所选压力的线性组合确定。 因为每条边的贡献都是对称的，所以一旦组件中的单个变量被固定，所有其他变量都会被强制。 这将每个组件的搜索空间减少到两个全局状态。 

该算法检查两种可能的状态并验证是否有任何顶点违反条件 Final[i] = a[i]。 由于所有约束都是通过传播直接强制执行的，因此任何有效的解决方案都必须出现在这两种状态之一中。 如果两者都不起作用，则该组件内的任何压力机分配都无法避免产生禁止的相等性，从而使全局解决方案变得不可能。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)
    
    a = list(map(int, input().split()))
    
    vis = [False] * n
    parent = [-1] * n
    comp = []

    def dfs(start):
        stack = [start]
        vis[start] = True
        comp_nodes = []
        
        while stack:
            u = stack.pop()
            comp_nodes.append(u)
            for v in g[u]:
                if not vis[v]:
                    vis[v] = True
                    parent[v] = u
                    stack.append(v)
        return comp_nodes

    def evaluate(root_choice):
        x = {}
        for v in comp:
            x[v] = -1
        
        root = comp[0]
        x[root] = root_choice
        
        stack = [root]
        while stack:
            u = stack.pop()
            for v in g[u]:
                if v in x and x[v] == -1:
                    x[v] = x[u]  # consistent propagation
                    stack.append(v)
        
        # compute final values
        ok = True
        final = {}
        for u in comp:
            s = x[u]
            for v in g[u]:
                if v in x:
                    s += x[v]
            final[u] = s
            if final[u] == a[u]:
                ok = False
        
        if not ok:
            return None
        return x

    ans = []

    for i in range(n):
        if vis[i]:
            continue
        comp = dfs(i)

        res0 = evaluate(0)
        if res0 is None:
            res1 = evaluate(1)
            if res1 is None:
                print(-1)
                return
            ans.append(res1)
        else:
            ans.append(res0)

    out = []
    for d in ans:
        for k, v in d.items():
            if v == 1:
                out.append(k + 1)

    print(len(out))
    print(*out)

if __name__ == "__main__":
    solve()
```DFS 将图拆分为连接的组件，以便每个组件都可以独立求解。 在每个组件内部，`evaluate`函数假设根的二元选择并将该选择传播到邻居之间。 每个节点都从访问的邻居继承其状态，从而在整个组件中构建一致的分配。 

传播后，代码通过对同一组件内每个节点及其邻居的贡献求和来重新计算最终值。 如果任何节点与其禁止值 a[u] 匹配，则该分配将被拒绝。 

最终输出收集所有组件中分配值 1 的所有节点。 

一个微妙的实施风险是将传播视为平等复制。 这只有效，因为在组件内，系统减少到单个自由度； 如果没有这个属性，单纯的复制将是不正确的。

 ## 边缘情况

 一个重要的边缘情况是完全孤立的顶点，其目标恰好为 1。在这种情况下，按下它会立即产生值 1 并导致损失。 该算法处理这个问题是因为在单例组件中，两个根选择都经过测试，并且当它们生成 a[i] 时都将被拒绝。 

另一个边缘情况是树组件，其中需要交替分配以保持一致性。 由于传播在组件内是均匀的，因此当节点与其禁止值匹配时，任何矛盾都会在评估期间立即显现出来，从而防止接受无效分配。 

最后的边缘情况是一个密集的组件，其中许多邻居相互加强。 即使在这种情况下，评估步骤也会显式地重新计算最终总和，因此无论结构如何，都会检测到与 a[i] 的任何意外匹配，从而确保正确性。
