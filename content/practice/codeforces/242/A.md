[CF 242A - 正面或反面](https://codeforces.com/problemset/problem/242/A)

 **评分：** 1100
 **标签：** 暴力破解、实施
 **求解时间：** 3m 26s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们知道每个玩家掷硬币的次数。 瓦夏翻转了`x`次和Petya翻转`y`次。 每个头都给出一分，每个尾部什么也不给出。 

瓦莱拉不记得具体的最终比分，但他记得三个事实。 瓦夏至少得到了`a`头，佩蒂亚至少得到了`b`瓦夏 (Vasya) 严格领先于佩蒂亚 (Petya)。 

我们必须打印每一对`(c, d)`这样：

 -`c`Vasya 的可能正面数量
 -`d`Petya 可能出现的头数
 -`a ≤ c ≤ x`-`b ≤ d ≤ y`-`c > d`输出对必须按字典顺序递增出现。 这意味着更小`c`首先，并且平等`c`, 较小`d`首先。 

限制很小。 每个值最多是`100`。 即使检查所有可能的对最多也只需要`101 × 101 = 10201`迭代，这对于 2 秒的限制来说是完全微不足道的。 这立即表明直接暴力枚举。 

这个问题中唯一真正的危险是不等式或迭代范围错误。 

一个容易犯的错误是允许平局。 Vasya一定是胜利者，所以条件很严格`c > d`， 不是`c ≥ d`。 

考虑这个输入：```
2 2 1 1
```可能的分数是：```
2 1
2 2
1 1
1 2
```仅有的`(2, 1)`是有效的，因为 Vasya 必须比 Petya 有更多的头。 粗心的实现使用`>=`会错误地包括`(1,1)`和`(2,2)`。 

当 Petya 的最低分数对于大多数 Vasya 分数来说已经太大时，就会发生另一个微妙的情况。 

例子：```
3 5 1 4
```Petya 总是至少有`4`头。 Vasya 最多可以拥有`3`。 不存在有效结果，因此正确的输出是：```
0
```如果一个粗心的解决方案盲目地打印范围内的所有对而不检查获胜者条件，那么这里将会失败。 

订购也很重要。 这些对必须已经按字典顺序排序。 如果我们迭代`c`从小到大，并且对于每个`c`迭代`d`从小到大，生成的订单自动满足要求。 

## 方法

 最直接的方法是尝试每一个可能的最终分数对。 

Vasya 的得分范围为`a`到`x`。 Petya 的得分范围为`b`到`y`。 对于每对`(c, d)`在这些范围内，我们检查是否`c > d`。 如果是，我们存储该对。 

这种暴力方法是正确的，因为每个有效的游戏结果都恰好对应于这些边界内的一对，并且我们输出的每一对都满足语句中的所有条件。 

蛮力方法已经完全符合限制。 最坏的情况下，我们测试了大约一万对，这是可以忽略不计的。 

这里没有隐藏的优化技巧，因为搜索空间已经非常小了。 真正的观察是认识到约束是故意很小的，因此直接实施是预期的解决方案。 尝试推导公式或复杂的修剪只会使代码更难以阅读，而不会以任何有意义的方式提高性能。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举| O((x - a + 1)(y - b + 1)) | O((x - a + 1)(y - b + 1)) | O(答案数) | 已接受 |
 | 优化数学推导| O(答案数) | O(答案数) | 不必要|

 ## 算法演练

 1.读取四个整数`x`,`y`,`a`， 和`b`。 
2. 创建一个空列表`ans`存储所有有效的分数对。 
3. 迭代 Vasya 的可能分数`c`从`a`到`x`。 

这些都是与Valera记忆中Vasya得分至少相符的数值`a`正面且不能超过翻转次数。 
4. 对于每个`c`, 迭代 Petya 的可能得分`d`从`b`到`y`。 

这些都是与 Petya 记忆的下限一致的值。 
5. 检查是否`c > d`。 

瓦夏必须严格赢得比赛。 相同分数对应平局，不得计入。 
6. 如果条件成立，则追加`(c, d)`到答案列表。 
7. 打印存储对的数量。 
8. 按照生成的顺序打印每对。 

因为`c`首先增加并且`d`增加第二个，输出会自动按字典顺序排序。 

### 为什么它有效

 该算法检查每个可能的分数对，以满足记住的下限和抛硬币次数所施加的物理限制。 

对于每一对，它都会检查问题的确切获胜条件。 不会错过任何有效的对，因为每个可行的结果都出现在嵌套循环中的某个位置。 无法打印无效对，因为我们仅添加 Vasya 分数严格大于 Petya 分数的对。 

迭代顺序自动保证字典顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x, y, a, b = map(int, input().split())

    ans = []

    for c in range(a, x + 1):
        for d in range(b, y + 1):
            if c > d:
                ans.append((c, d))

    print(len(ans))

    for c, d in ans:
        print(c, d)

solve()
```该程序直接遵循上述算法。 

外循环迭代 Vasya 的所有可能分数。 内循环迭代 Petya 的所有可能分数。 条件`c > d`完全符合瓦西亚获胜的要求。 

使用范围`x + 1`和`y + 1`因为Python的`range`不包括上端点。 忘记了`+1`会错误地跳过最大可能分数。 

答案在打印之前存储，因为第一个输出行必须包含有效对的总数。 我们只有在枚举结束后才知道计数。 

顺序要求由循环结构自然地处理。 自从`c`单调增加，并且`d`对于每个固定值单调增加`c`，生成的序列已经正确排序。

 | 测量| 复杂性 | 说明|

 因为所有的值最多都是`100`，总迭代次数最多一万次左右。 与时间限制相比，这个时间很小，因此该解决方案可以轻松满足时间和内存的限制。 

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    x, y, a, b = map(int, input().split())

    ans = []

    for c in range(a, x + 1):
        for d in range(b, y + 1):
            if c > d:
                ans.append((c, d))

    out = [str(len(ans))]

    for c, d in ans:
        out.append(f"{c} {d}")

    print("\n".join(out))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("3 2 1 1\n") == (
    "3\n"
    "2 1\n"
    "3 1\n"
    "3 2\n"
), "sample 1"

# minimum-size input
assert run("1 1 1 1\n") == (
    "0\n"
), "minimum case"

# exactly one valid pair
assert run("2 1 2 1\n") == (
    "1\n"
    "2 1\n"
), "single valid answer"

# no valid outcomes
assert run("3 5 1 4\n") == (
    "0\n"
), "Petya always ahead or tied"

# boundary ordering check
assert run("3 3 1 1\n") == (
    "3\n"
    "2 1\n"
    "3 1\n"
    "3 2\n"
), "lexicographical order"

# maximum-size style case
out = run("100 100 100 100\n")
assert out == "0\n", "largest equal bounds"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`1 1 1 1`|`0`| 最低限度的约束和严格的不平等|
 |`2 1 2 1`| 一对`(2,1)`| 精确边界包含|
 |`3 5 1 4`|`0`| 不存在有效结果 |
 |`3 3 1 1`| 订购有效对| 字典顺序|

 ## 边缘情况

 考虑尽可能最小的输入：```
1 1 1 1
```该算法仅检查一对：

 | c | d | c > d |
 | --- | --- | --- |
 | 1 | 1 | 没有 |

 由于条件失败，答案列表保持为空并且程序打印：```
0
```这可以正确处理抽屉。 

现在考虑 Petya 的最低记忆分数已经太高的情况：```
3 5 1 4
```外循环产生`c = 1, 2, 3`。 内循环产生`d = 4, 5`。 每次比较都会失败，因为`c`永远不会大于`d`。 

该算法正确地打印出没有有效结果。 

最后，考虑一个顺序敏感的示例：```
4 3 2 1
```生成的有效对是：```
2 1
3 1
3 2
4 1
4 2
4 3
```嵌套循环自然会产生字典顺序，因为`c`先增加，然后`d`。 不需要额外的排序步骤。
