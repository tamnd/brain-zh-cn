 ## 解决方案
 ## 问题理解

 我们得到一个十进制数作为字符串。 该数字包含一个整数部分，然后是一个点，然后是一个小数部分。 任务是模拟王国奇怪的舍入规则。 

这些规则故意不完整。 如果整数部分以数字结尾`9`，除了 Vasilisa 之外没有人可以处理进位操作，所以我们必须打印：```
GOTO Vasilisa.
```否则，我们只查看小数点后的第一位数字。 如果它小于`5`，我们向下舍入并打印整数部分不变。 如果至少是`5`，我们将整数部分增加`1`。 

输入长度最大可达 1000 个字符。 这立即告诉我们问题是关于字符串处理，而不是数值计算。 将整个值转换为浮点数会很危险，因为浮点类型会失去长输入的精度。 甚至不需要转换为普通整数。 我们只需要字符串中的几个字符。 

对于线性处理来说，时间限制很宽裕。 对于长度为 1000 的字符串，即使扫描一次整个字符串也是微不足道的。任何时间复杂度为 O(n) 或更好的解决方案都很容易适合。 

有几种边缘情况可能会悄悄破坏粗心的实现。 

第一个是当整数部分以以下结尾时`9`。 

输入：```
19.1
```正确输出：```
GOTO Vasilisa.
```一个幼稚的实现可能仍然尝试进行数字舍入并产生`19`，但该声明明确禁止在这种情况下处理进位。 

另一个微妙的情况是小数部分有很多位。 

输入：```
12.499999999
```正确输出：```
12
```只有小数点后的第一位数字很重要。 其余数字必须被忽略。 将整个小数值视为实数可能会带来不必要的复杂性。 

第三种边缘情况是最小的可能整数。 

输入：```
0.5
```正确输出：```
1
```整数部分可以为零，因此实现不得意外地将结果剥离为空字符串。 

一种更重要的情况是当数字已经接近进位边界但仍然允许时。 

输入：```
8.9
```正确输出：```
9
```整数部分不以`9`，所以加一是有效的。 

## 方法

 暴力方法将解析整个十进制数并执行普通舍入。 一种可能的实现是使用任意精度的十进制算术或手动将小数部分与`0.5`。 

这在逻辑上是有效的，因为舍入规则几乎是标准舍入规则。 当我们记住对以结尾的整数部分的特殊限制时，问题就出现了`9`。 通用数字舍入实现会错误地舍入诸如`19.7`进入`20`，即使所需的输出是`"GOTO Vasilisa."`。 

蛮力思想也做了不必要的工作。 输入最多可以包含 1000 个字符，但答案仅取决于两个字符：

 1. 点前的最后一位数字。 
2. 点后的第一位数字。 

该观察立即给出了最佳解决方案。 我们在小数点周围分割字符串，检查这两个位置，然后直接决定答案。 

如果整数部分结尾为`9`，我们打印特殊消息。 

否则：

 1. 如果第一个小数位小于`5`，打印整数部分。 
2.如果至少是`5`，打印增加的整数部分`1`。 

因为整数部分永远不会以`9`在第二种情况下，添加一个永远不会导致进位链。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 已接受但没有必要 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取输入字符串。 

该数字以文本形式提供，将其视为文本可以避免精度问题。 
2. 将小数点处的字符串拆分为`integer_part`和`fractional_part`。 

该问题保证恰好有一个点，因此分裂是安全的。 
3. 检查最后一位数字`integer_part`。 

如果这个数字是`'9'`， 打印：```
GOTO Vasilisa.
```并停止。 

该声明明确指出以`9`无法正常舍入。 
4. 查看第一个数字`fractional_part`。 

这个数字本身就决定了我们是向上舍入还是向下舍入。 
5. 如果数字小于`'5'`， 打印`integer_part`。 

数字向下舍入。 
6. 否则，转换`integer_part`为一个整数，加一，然后打印结果。 

由于最后一位数字不是`9`，这种加法永远不会创建进位链。 

### 为什么它有效

 舍入规则仅取决于小数部分是否低于`0.5`或者至少`0.5`。 在十进制表示法中，该比较完全由小数点后的第一位数字决定。 

如果第一个小数位是：

 -`0`通过`4`，该值严格低于`0.5`。 
-`5`通过`9`，该值至少为`0.5`。 

特别的`"GOTO Vasilisa."`每当整数部分以以下结尾时，条件就会覆盖其他所有内容`9`。 由于算法首先检查该条件，因此每个可能的输入都完全遵循所需的规则集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()

integer_part, fractional_part = s.split('.')

if integer_part[-1] == '9':
    print("GOTO Vasilisa.")
else:
    if fractional_part[0] < '5':
        print(integer_part)
    else:
        print(int(integer_part) + 1)
```解决方案首先将数字读取为字符串。 这是最安全的方法，因为输入可能很长，并且不需要浮点运算。 

分割运算将整数部分和小数部分完全分开。 由于该语句保证有效的十进制表示形式，因此始终只有一个点。 

最重要的实施细节是检查的顺序。 我们必须测试整数部分是否以`9`在尝试任何舍入之前。 否则，输入类似`19.7`会错误地变成`20`。 

对比`'5'`作为字符比较完成，这是有效的，因为数字字符按照与其数值相同的顺序按字典顺序排序。 

最后添加使用`int(integer_part) + 1`。 这是安全的，因为整数部分长度最多为 999 位数字，Python 可以自然地使用任意精度整数来处理它。

## 测试用例```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    s = input().strip()

    integer_part, fractional_part = s.split('.')

    if integer_part[-1] == '9':
        print("GOTO Vasilisa.")
    else:
        if fractional_part[0] < '5':
            print(integer_part)
        else:
            print(int(integer_part) + 1)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("0.0\n") == "0\n", "sample 1"

# custom cases
assert run("8.9\n") == "9\n", "round up without carry"
assert run("19.1\n") == "GOTO Vasilisa.\n", "integer part ends with 9"
assert run("12.499999\n") == "12\n", "ignore remaining fractional digits"
assert run("0.5\n") == "1\n", "minimum integer rounding up"
assert run("12345678987654321.4\n") == "12345678987654321\n", "large integer round down"

 ## 边缘情况

 考虑禁止携带的情况。 

输入：```
29.8
```该算法首先提取`integer_part = "29"`和`fractional_part = "8"`。 

整数部分的最后一位数字是`'9'`，所以算法立即打印：```
GOTO Vasilisa.
```它从不尝试舍入。 这完全符合问题规则。 

现在考虑一个误导性的小数部分。 

输入：```
7.499999999
```该算法仅检查第一个小数位，即`'4'`。 自从`'4' < '5'`，结果变为：```
7
```尽管后面的数字都是`9`，这个数字仍然严格小于`7.5`。 

最后，考虑从零开始舍入。 

输入：```
0.7
```整数部分不以`9`，第一个小数位是`'7'`，因此算法计算：```
0 + 1 = 1
```并打印：```
1
```这确认了实现正确处理最小的有效整数。
