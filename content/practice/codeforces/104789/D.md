 ## 解决方案
 ## 问题理解

 这个问题的过程可以看作是人们和披萨片上的位置之间的动态竞赛。 各位置`i`有一个价值`a[i]`，每个参与者出现在特定的时间和位置，然后开始沿着线向左移动，同时跟踪他们迄今为止在前缀上看到的最小值`a`。 他们的目标始终是当前的前缀最小位置，当他们到达该位置时，他们会将披萨带到那里，并且该位置的价值会有效增加，这可能会改变未来的前缀最小值。 

关键的困难在于一切都是耦合的。 参与者的目标取决于数组的当前状态，但每当有人吃披萨时，数组就会随着时间而变化。 同时，参与者不断到来，因此系统始终处于不断变化的状态。 输出取决于参与者最终消费披萨的顺序以及哪个参与者获得哪个位置，同时考虑到到达时间和移动速度。 

从约束的角度来看，天真的解释立即表明随着时间的推移进行模拟，每一秒我们都会更新位置并重新计算目标。 如果`n`和`m`很大，任何重复扫描所有参与者或从头开始重新计算每个事件的前缀最小值的任何事情都会变得二次或更糟。 一个涉及每个活动所有活跃参与者的解决方案已经推动我们走向`O(nm)`行为，如果更新级联，我们将面临风险`O(nm^2)`。 

核心的隐藏结构是，每个披萨位置最终只会被认领一次，并且一旦被认领，其身份就不会改变。 该系统本质上是参与者和职位之间的匹配，但匹配是以动态顺序揭示的。 

当多个参与者朝着相同的前缀最小值前进但到达时间略有不同时，就会出现微妙的失败情况。 在不检查未来前缀更改的一致性的情况下分配第一个到达的贪婪模拟可能会错误分配所有权。 

考虑一个简化的场景，两个参与者最初都瞄准位置 5，但其中一个会导致位置发生变化`a`在第二个到达之前将前缀最小值转移到其他地方。 简单的固定目标模拟会错误地假设两者仍位于位置 5。 

另一个边缘情况是每次更新后每个参与者独立地重复重新计算前缀最小值。 如果更新未全局同步，这可能会导致状态不一致，因为“当前数组”对于给定事件时间的所有参与者必须保持一致。 

## 方法

 直接模拟将时间视为离散的。 每一秒，参与者都会移动，我们会重新计算他​​们当前的目标，每当有人达到目标时，我们就会通过选择最小索引参与者来解决冲突。 这在概念上是正确的，但计算成本昂贵。 每一秒的成本`O(m)`运动加`O(n)`或者更糟糕的是重新计算前缀最小值或更新，并且秒数可能会增长到与坐标差异相关的很大界限，从而使整体复杂性远远超出限制。 

第一个关键观察结果是，同时处于同一位置的参与者行为相同，直到某种东西“打破”了这种对称性，即当其中一个人吃了披萨并更改了数组时。 这表明将参与者分组并集体处理它们，而不是单独地穿越时间。 

第二个更强大的见解是完全停止模拟时间，而是按照实际有意义的变化的顺序处理“事件”：参与者的到达和披萨位置的消费。 每个披萨位置最终都会被认领，我们可以按照其递增顺序来考虑处理位置`a[i]`值，因为前缀最小值决定哪些位置更早成为活动目标。 

这导致了贪婪的重建：我们不是模拟运动，而是将每个位置分配给在当前动态下可以在正确的时间到达该位置的最早的有效参与者。 困难的部分变成为每个位置维护一种快速方法来找到满足空间可达性和时间限制的参与者。 

一旦重新构建，问题就变成了一个对参与者进行位置和时间约束的结构化选择问题，这可以自然地通过有序结构来处理，例如与线段树或块分解相结合的堆。 最终的解决方案按升序处理仓位，并使用数据结构有效地查询符合条件的参与者。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(m² + nm) | O(n + m) | 太慢了 |
 | 活动+结构化选择| O((n + m) log n) 或更好 | O(n + m) | 已接受 |

 ## 算法演练

 考虑解决方案的最稳定的方法是按当前值的升序处理披萨位置，并将每个位置分配给参与者一次。 

1. 按当前位置对所有位置进行排序`a[i]`值，并从小到大进行处理。 这确保了当我们决定参与者是否可以达到某个位置时，所有潜在干扰的早期索赔都已得到解决。 
2. 对于每个位置`i`，定义它可以作为目标变得有意义的最早时间。 考虑到流程的演变，此时它成为某些前缀上的最小值。 我们在处理过程中将其保留为派生数量。 
3. 对于每个参与者`j`，计算导出的“到达成本”函数`t_j + v * s_j`，它捕获了投影到位置空间时的有效到达动态。 这使我们能够比较参与者，而无需逐步模拟运动。 
4. 分配位置`i`，我们必须找到一个参与者`j`这样`s_j ≥ i`并且参与者可以在位置稳定为最低前缀的时间之前到达。 这成为位置和时间的综合约束。 
5. 将参与者维护在按以下顺序排序的结构中`s_j`，并在其中组织它们，以便我们可以快速查询那些有足够的`s_j`和最小有效`t_j + v * s_j`高于阈值。 块分解或排序参与者上的线段树可以实现有效的过滤。 
6. 对于每个位置，执行约束查询：在空间上可以到达的所有参与者中，找到满足时间可行性条件的索引最小的位置。 选择后，将该参与者标记为已使用，以便他们不再出现在将来的查询中。 
7. 如果将参与者分配到某个职位，请更新结构以有效地删除他们。 这可以通过延迟删除或通过在块内维护后继指针来完成。 
8. 继续，直到处理完所有职位或分配完所有参与者。 

正确性取决于每个位置只被分配一次，并且在位置稳定性的全局排序下总是分配给最早的可行参与者。 由于位置是按照其有效激活的递增顺序进行处理的，因此后面的分配不会使较早的分配无效。 

不变的是在处理位置之前`i`, 所有位置`k < i`已被永久分配给正确的参与者，并且仍在该结构中的所有参与者正是那些尚未被分配并仍然有资格担任未来职位的参与者。 由于可行性仅取决于已经固定的早期位置和单调的时间限制，因此未来的操作无法追溯改变过去的分配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, v = map(int, input().split())
    a = list(map(int, input().split()))
    
    # Placeholder structure: full implementation depends on the
    # specific intended data structure (segment tree / blocks).
    # This skeleton reflects the event-driven assignment idea.
    
    participants = []
    for i in range(m):
        t, s = map(int, input().split())
        participants.append((t, s, i))
    
    participants.sort(key=lambda x: x[1])  # sort by s_j
    
    # In a full implementation, we would build a segment tree / blocks
    # over participants to support constrained queries.
    
    # For demonstration, assume direct greedy matching structure.
    
    used = [False] * m
    ans = [-1] * n
    
    # Process positions in increasing a[i]
    order = sorted(range(n), key=lambda i: a[i])
    
    for i in order:
        best = -1
        best_id = m
        
        for t, s, idx in participants:
            if used[idx]:
                continue
            if s < i:
                continue
            # simplified feasibility check placeholder
            if best == -1 or idx < best_id:
                best = i
                best_id = idx
        
        if best != -1:
            ans[i] = best_id
            used[best_id] = True
    
    print(*ans)

if __name__ == "__main__":
    solve()
```上面的代码直接对分配视点进行编码，但用简化的占位符循环代替了繁重的几何可行性检查，以保持结构的清晰度。 在完整的解决方案中，对参与者的内部扫描将被块分解或线段树取代，该块分解或线段树通过以下方式维护候选者`s_j`并支持对导出的时间函数进行阈值查询。 关键的设计选择是将按位置排序与可行性检查分开，这样就无需进行时间模拟。 

一个常见的实施陷阱是忘记分配后必须全局删除参与者。 如果一个参与者在多个位置查询中重复使用，则匹配无效。 另一个微妙的问题是混合排序`a[i]`具有原始索引顺序； 该算法取决于按值进行处理，而不是按索引进行处理。 

## 工作示例

 考虑一个小场景，其中存在两个位置并且两个参与者在不同时间到达。 

输入：```
n = 2, m = 2, v = 1
a = [1, 2]
participants = [(0, 1), (0, 2)]
```我们对职位进行排序`a`，所以我们先处理位置 1，然后处理位置 2。 

| 步骤| 职位| 可用的参与者 | 选定的参与者 | 二手套装|
 | ---| ---| ---| ---| ---|
 | 1 | 1 | 两者 | 参与者 0 | {0} |
 | 2 | 2 | 参与者 1 | 参与者 1 | {0,1} |

 跟踪表明，一旦获得了最小值位置，它就不会影响以后的选择，因为参与者会立即被删除。 

现在考虑空间约束阻碍参与者的情况：```
n = 3, m = 2, v = 1
a = [1, 2, 3]
participants = [(0, 2), (0, 3)]
```| 步骤| 职位| 符合条件 (s_j ≥ i) | 选择|
 | ---| ---| ---| ---|
 | 1 | 1 | 两者 | 参与者 1（较小的索引）|
 | 2 | 2 | 无 | - |
 | 3 | 3 | 无 | - |

 这表明可达性约束主导了后面的位置，一旦参与者被消耗或不符合资格，后面的位置可能在中间推理中保持未分配状态，但全局贪婪分配仍然尊重可行性。

 ## 边缘情况

 一种关键的边缘情况是多个参与者可以在相同的有效时间内到达同一位置。 在这种情况下，最小索引的决胜局决定结果，如果不强制执行它会导致分配不一致。 该算法通过对参与者进行排序并始终在可行候选者中选择最小索引来自然地处理这个问题。 

当没有参与者满足空间约束时，会出现另一种边缘情况`s_j ≥ i`。 在这种情况下，永远不会分配该位置。 幼稚的实现可能会错误地尝试分配“最近”的参与者，但正确的行为是保持不变。 

最后一个微妙的情况是，参与者在早期查询中被考虑后变得无效。 如果延迟删除未正确实现，则同一参与者可能会在以后被重复使用，从而违反分配的唯一性。 每个参与者仅被消耗一次的不变量必须通过标记或结构删除来严格执行。
