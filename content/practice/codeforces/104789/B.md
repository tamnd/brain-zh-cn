 ## 解决方案
 ## 问题理解

 我们有一个重复的时间表，在工作日和休息日之间交替。 一个完整的模式由一个块组成`x`接下来的工作日`y`休息日，然后永远重复。 这意味着整个时间线是周期性的`x + y`。 

我们也有几天的时间`d1, d2, ..., dn`。 这些天中的每一天都必须属于一个工作段。 但是，我们可以选择周期的起始对齐方式，这意味着我们选择一天`D`代表工作块的第一天，然后循环继续进行`x`天，然后休息`y`日子，重复着。 

任务是确定是否存在这样的转变`D`这样每一天`di`落在定期计划的工作间隔内。 如果存在这样的转变，我们必须输出它； 否则，我们输出这是不可能的。 

关键的结构约束是周期性模`x + y`。 任何两个候选比对仅因该循环中的移位而不同，因此所有推理都可以简化为残基模`x + y`。 

输入大小允许最大`n`，所以任何天数的二次方或线性`(x + y)`当两者都很大时就变得不可行。 这推动我们走向`O(n log n)`或者`O(n)`纯粹以模算术工作的解决方案。 

当间隔“环绕”循环边界时，会出现一个微妙的问题。 循环空间中的有效工作间隔可能看起来像单个段或分成两部分，并且除非我们明确正确地处理模块化换行，否则天真的线性间隔处理会中断。 

一种常见的失败情况是当人们尝试分配每个`di`独立地不考虑相交约束。 每个`di`限制循环可以从哪里开始，并且这些限制必须在全局范围内结合起来。 

## 方法

 直接的暴力方法确定了候选人的开始日期`D`在`[1, x + y]`并检查每个给定的`di`。 对于固定的`D`，我们计算`(di - D) mod (x + y)`并验证它位于`[0, x - 1]`。 如果所有日子都满足这个条件，`D`是有效的。 

这是正确的，因为时间表一次就完全确定了`D`是固定的。 然而，尝试一切`D`价值成本`O((x + y) * n)`，当两个参数都很大时，它会变得太慢。 

关键的观察是每个`di`没有定义单个有效的`D`，而是循环空间中一系列可能的起始位置。 对于给定的`di`，必须放置循环起点，以便`di`落在工作段内。 这转化为对`D`模数`x + y`，在圆上形成一个区间。 

我们不是独立检查每个候选者，而是将所有这些循环间隔相交。 当且仅当交集非空时答案才存在。 

然后，问题就简化为维护圆上间隔的交集，这可以通过对端点进行排序和扫描或通过将循环间隔分割成线性段来处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解 D | O(n(x+y)) | O(n(x+y)) | O(1) | O(1) | 太慢了 |
 | 圆上的区间交点 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将一切都转换成模空间`m = x + y`。 

1. 每天`di`，计算有效周期开始的集合`D`这样`di`位于工作区间。 这意味着`di - D mod m < x`。 重新排列给出了约束`D`以循环形式。 
2. 每个约束成为一个循环区间`[0, m-1]`。 取决于是否`di`接近边界时，该区间可能会环绕。 
3. 为了处理环绕，将每个循环间隔分成最多两个标准间隔`[0, m-1]`。 
4. 将问题转化为找点问题`D`同时位于所有区间内，这意味着我们与所有区间约束相交。 
5、维持全局可行范围。 从整圈开始`[0, m-1]`。 
6. 对于每个区间约束，通过将其与当前集合相交来更新可行区域。 如果在任何一点可行区域变空，则不存在解。 
7. 如果存在非空区域，则输出其中任意点作为有效起始日`D`。 

### 为什么它有效

 每个`di`独立地精确定义了使其进入工作段的一组循环班次。 任何有效的全局对齐必须同时满足所有约束，因此正确的解决方案正是所有这些集合的交集。 因为所有约束都是从固定周期内的模运算导出的，所以除了循环区间交集之外不需要额外的结构，并且交集保留了正确性而不会引入伪解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def normalize(l, r, m):
    if l <= r:
        return [(l, r)]
    return [(l, m - 1), (0, r)]

def intersect(a, b):
    res = []
    i = j = 0
    while i < len(a) and j < len(b):
        l = max(a[i][0], b[j][0])
        r = min(a[i][1], b[j][1])
        if l <= r:
            res.append((l, r))
        if a[i][1] < b[j][1]:
            i += 1
        else:
            j += 1
    return res

def solve():
    n, x, y = map(int, input().split())
    m = x + y
    ds = list(map(int, input().split()))

    # initial feasible set is whole circle
    cur = [(0, m - 1)]

    for d in ds:
        # we need D such that d lies in [D, D+x-1] mod m
        # equivalent to D in [d-x+1, d] mod m
        l = (d - x + 1) % m
        r = d % m

        intervals = normalize(l, r, m)
        cur = intersect(cur, intervals)
        if not cur:
            print("NO")
            return

    # pick any valid D
    D = cur[0][0]
    print("YES")
    print(D)

if __name__ == "__main__":
    solve()
```该实现将可行区域保持为圆上不相交线段的并集。 每个新约束都会转换为一个或两个线性线段，并使用两指针合并与当前集合相交。 

关键的微妙之处在于环绕处理。 一个约束`[l, r]`在哪里`l > r`不能被视为无效； 相反，它代表两个有效段`[l, m-1]`和`[0, r]`。 

另一个微妙的点是我们始终保持不相交的排序间隔，这允许线性时间合并。 如果没有这个不变量，重复的交叉可能会退化为二次行为。 

## 工作示例

 ### 示例 1

 假设`x = 3, y = 2`， 所以`m = 5`， 和`d = [2, 3, 7]`。 

我们跟踪可行的区间：

 | 步骤| d | 约束 [l, r] mod 5 | 可行集 |
 | ---| ---| ---| ---|
 | 初始化| - | - | [0,4]|
 | 1 | 2 | [0,2]| [0,2]|
 | 2 | 3 | [1,3]| [1,2]|
 | 3 | 7（2 模 5）| [0,2]| [1,2]|

 最终可行集为`[1,2]`，因此存在有效答案。 

该跟踪表明每个`di`逐渐缩小允许的对齐范围，直到只剩下一致的循环开始。 

### 示例 2

 让`x = 2, y = 3`， 所以`m = 5`， 和`d = [1, 4]`。 

| 步骤| d | 约束| 可行集 |
 | ---| ---| ---| ---|
 | 初始化| - | - | [0,4]|
 | 1 | 1 | [4,1] → [4,4] ∪ [0,1] | [4,4] ∪ [0,1] |
 | 2 | 4 | [2,4]| 交集变为 [4,4] |

 最终答案是`D = 4`。 

这演示了环绕约束，并说明了为什么需要分割循环间隔。

 ## 边缘情况

 当约束环绕模量边界时，会出现常见的边缘情况。 例如，与`x = 4, y = 3, m = 7`， 和`d = 1`，有效开始间隔变为`[5, 1]`。 简单的区间交集会将其视为无效，但正确的解释是两个不相交的段。 该算法明确地将其分为`[5,6]`和`[0,1]`，并且交集正确进行。 

当所有情况都出现时，会出现另一种边缘情况`di`模数相同`m`。 在这种情况下，每个约束都完美重叠，并且可行区域缩小到一个点。 该算法通过从不合并有效的单例间隔来保留这一点。 

最后的边缘情况是约束提前消除了所有位置。 一旦可行集变空，算法立即停止，避免不必要的计算，同时保证正确性，因为未来的交集无法恢复空集。
