 ## 解决方案
 ## 问题理解

 锦标赛可以被视为奶牛数组上的完整二叉树。 

每片叶子都是一头牛。 每个内部节点代表一段连续的奶牛。 节点的技能是该段内所有值的异或。 当一个节点的两个子节点发生冲突时，异或较大的子节点获胜，如果异或相等，则左子节点获胜。 

获胜的筹码堆放在失败的筹码堆之上。 

对于每个查询，只有一头牛暂时改变其技能值。 我们运行整个锦标赛，并且必须确定最终堆栈中有多少头牛高于该头牛。 

奶牛的数量是$2^n$， 和$n \le 18$。 在所有测试用例中，奶牛总数最多为$2^{18}$，查询总数最多为$2 \cdot 10^5$。 

一场锦标赛的完整模拟需要处理所有$2^n-1$匹配。 在最大的测试中，大约是$2.6 \cdot 10^5$每个查询的操作。 乘以$2 \cdot 10^5$查询是完全不可能的。 

的小值$n$才是真正的线索。 一头牛每轮只参加一场比赛，因此它只参与$n \le 18$匹配。 任何仅处理从修改后的叶子到根的路径的解决方案都立即处于正确的复杂性范围内。 

简单的实现可能会在很多地方出错。 

考虑打领带。 如果左段有 XOR 5 并且右段也有 XOR 5，则左段获胜。 比较使用`>=`对于双方来说都是不正确的。 

例如：```
2 cows
5 5
```左边的牛获胜，所以最终的堆栈是：```
right, left
```左边的牛上面有 0 头牛，右边的牛上面有 1 头。 

另一个容易犯的错误是假设堆栈顺序会影响未来的 XOR 值。 事实并非如此。 XOR 仅取决于哪些奶牛属于堆栈，而不取决于它们的顺序。 一旦我们认识到这一点，每个分段的技能只是其区间的异或。 

第三个错误是试图跟踪整个堆栈。 我们只需要一头牛的位置。 段内的相对顺序永远不会改变。 唯一重要的是包含我们的牛的片段是否赢得或输掉每场祖先比赛。 

## 方法

 暴力解决方案很简单。 

对于每个查询，更改所选牛的值，模拟所有锦标赛轮次，构建结果堆栈，最后在最终堆栈中找到修改后的牛。 

一场锦标赛于$N=2^n$奶牛含有$N-1$匹配。 的最大值$N$是 262144。最多$2 \cdot 10^5$查询，这大致变成$5 \cdot 10^{10}$操作，远远超出极限。 

关键的观察结果是，修改后的牛仅影响锦标赛树的一条从根到叶的路径。 

更改叶子值$a_b$到$c$将每个祖先段的 XOR 更改相同的量：$$\Delta = a_b \oplus c.$$不包含那头牛的每个段都保持与以前完全相同的异或。 

现在想想修改后的牛的最终位置。 

在某个祖先节点，它的段与兄弟段竞争。 

如果它的段获胜，则同级段将排在下面。 我们的牛上方没有出现新的牛。 

如果其段丢失，则同级段将被放置在顶部。 该兄弟段中的每头牛都高于我们的牛。 

所以答案很简单：$$\sum \text{(size of sibling segment)}$$超过母牛一方输掉的所有祖先比赛。 

一头牛只有$n$祖先。 我们可以从叶子走到根，沿着该路径重新计算修改后的异或并确定其一方是否赢得每场比赛。 

这给出了$O(n)$询问。 

我们首先构建一次锦标赛树，存储每个段的异或。 然后每个查询只涉及$n \le 18$一条路径上的节点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(qN)$|$O(N)$| 太慢了|
 | 最佳|$O(N + q\log N)$|$O(N)$| 已接受 |

 ## 算法演练

 ### 预处理

 构建一棵完全二叉树，其叶子是奶牛值。 

对于每个内部节点，存储其两个子节点的异或。 

这给出了锦标赛中每个部分的异或。 

### 回答查询

 假设牛`b`变化自`a[b]`到`c`。 

让$$\Delta = a[b] \oplus c.$$修改后的叶子值很简单`c`。 

现在从那片叶子向上走到根部。 

1. 设置`cur`到当前节点的修改后的 XOR。 

最初这是`c`，因为当前节点是叶子本身。 
2. 在父节点上，确定兄弟节点。 
3.让`sib`是该同级段的存储的 XOR。 
4. 决定包含改造牛的一方是否获胜。 

如果我们这边是左孩子，则在以下情况下获胜：$$cur \ge sib$$因为领带向左。 

如果我们这边是正确的孩子，那么只有在以下情况下才会获胜：$$cur > sib$$5. 如果我方输了，则将兄弟段的大小添加到答案中。 

该段中的每头牛都将堆放在我们的牛上方。 
6. 计算父段的异或：$$cur = cur \oplus sib$$这是父区间的修改后的 XOR。 
7. 移动到父级并重复直到到达根。 
8. 输出累计答案。 

### 为什么它有效

 对于每个内部节点，其子节点之一正好堆叠在另一个节点之上。 

修改后的牛始终保留在该节点的一个子节点内。 

如果该孩子获胜，则兄弟段将移至下方，并且对修改后的母牛上方的母牛数量没有任何贡献。 

如果该孩子输了，则整个兄弟段都会放置在其上方。 该兄弟段中的每头牛都位于修改后的牛上方，贡献的大小恰好等于该段的大小。 

这些贡献在树的各个级别都是独立的。 每头位于改良牛上方的牛都属于改良牛一侧丢失的恰好一个祖先的兄弟部分。 

将那些丢失的兄弟片段的大小相加，将修改后的牛上方的每头牛都计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, q = map(int, input().split())
        m = 1 << n

        a = list(map(int, input().split()))

        size = m
        seg = [0] * (2 * size)

        for i in range(m):
            seg[size + i] = a[i]

        for i in range(size - 1, 0, -1):
            seg[i] = seg[i << 1] ^ seg[i << 1 | 1]

        for _ in range(q):
            b, c = map(int, input().split())
            pos = b - 1

            node = size + pos
            cur = c
            ans = 0

            seg_size = 1

            while node > 1:
                parent = node >> 1

                if node & 1:
                    sibling = node - 1
                    sib_xor = seg[sibling]

                    if cur <= sib_xor:
                        ans += seg_size
                else:
                    sibling = node + 1
                    sib_xor = seg[sibling]

                    if cur < sib_xor:
                        ans += seg_size

                cur ^= sib_xor
                node = parent
                seg_size <<= 1

            print(ans)

solve()
```该树存储在标准迭代线段树布局中。 

叶子占据位置`size ... 2*size-1`。 每个内部节点都存储其段的异或。 

对于查询，我们从不修改树。 查询是独立的，因此重建或更新会造成浪费。 

变量`cur`将修改段的 XOR 值存储在当前路径上。 在叶子上它等于`c`。 向上移动一级后，就变成了整个父段在假设修改下的异或。 

变量`seg_size`存储当前级别的同级段的大小。 在叶级别，同级包含一头牛。 每次上升后，路段大小都会加倍。 

比较是微妙的部分。 

当我们的段是左孩子时，平局就是胜利，所以失败意味着：```
cur < sib_xor
```当我们的细分市场是右子时，平局就是损失，因此损失意味着：```
cur <= sib_xor
```错误地理解这些不等式会导致平局案件的错误答案。 

## 工作示例

 ### 示例 1```
n = 2
a = [1, 3, 5, 7]
query: cow 1 becomes 1
```修改后的值不变。

 | 1 | 1 | 3 | 左| 是的 | 1 |
 | 2 | 2 | 2 | 左| 没有 | 0 |

 最终答案：```
1
```第一场比赛输了，因此奶牛 2 的结局高于奶牛 1。第二场比赛获胜，因为平局向左。

```| 水平| 我们的异或| 兄弟异或| 侧面| 失去？ | 添加|

这些痕迹说明了中心不变量：答案正是修改后的牛一侧失去的来自祖先匹配的兄弟片段的总大小。

 ## 边缘情况

 ### 两个段之间的关系

 输入：```
1
1 1
5 5
2 5
```右边的牛有 XOR 5，面对的是有 XOR 5 的左段。 

因为领带向左移动，所以右侧部分会失败。 左边的部分堆叠在它的上方，因此一头牛在 2 头牛的上方结束。 

该算法通过对右子节点进行严格比较来处理此问题。 自从`cur <= sibling`，添加兄弟尺寸。 

### 改良牛赢得每场比赛

 输入：```
1
2 1
1 2 3 4
4 100
```修改后的值主导其路径上的每次比较。 

没有同级段堆叠在其上方。 

该算法从不添加任何段大小，从而产生答案`0`。 

### 改良牛输掉每一场比赛

 输入：```
1
2 1
8 1 8 1
2 1
```奶牛 2 在第一级失败，其产生的片段在下一级再次失败。 

答案变成：```
1 + 2 = 3
```这正是锦标赛中其他奶牛的数量。 

每个损失都会贡献该级别的同级段的大小，并且算法会正确累积这两个贡献。
