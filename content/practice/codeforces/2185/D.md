 ## 解决方案
 ## 问题理解

 我们从一个数组和一系列更新操作开始。 每一项操作都会为一个位置增加一些价值。 

不寻常的部分是崩溃规则。 每次更新后，如果当前数组的任何元素变得大于`h`，电脑立即死机。 当发生这种情况时，整个数组将重置回其原始状态，而不是上次操作之前的状态。 

我们必须按顺序处理所有操作，并在每次崩溃和重置后输出最终数组。 

约束是塑造解决方案的首要因素。 在所有测试用例中，数组元素和操作的总数最多为`2·10^5`。 这意味着`O(n + m)`或者`O((n+m) log n)`解决方案很容易足够快。 另一方面，任何在每次操作后扫描整个数组的方法都需要最多`O(nm)`工作，这变成了关于`4·10^10`在最坏的情况下操作是完全不可行的。 

该问题最危险的部分是重置行为。 崩溃不仅仅撤消最后的操作。 它从测试用例的开头恢复原始数组。 

考虑：```
n = 2, h = 5
a = [1, 1]

operations:
(1, 3)
(1, 3)
```第一次更新后我们得到`[4,1]`。 

第二次更新后我们得到`[7,1]`，崩溃了。 

正确的状态变为`[1,1]`， 不是`[4,1]`。 

仅恢复最后一个操作的解决方案将产生错误的答案。 

另一个微妙的情况是自最近重置以来累积了多次更新：```
a = [0]
h = 5

operations:
+2
+2
+2
```这些州是：```
[2]
[4]
[6] -> crash -> [0]
```最终的答案是`[0]`。 

溢出检查必须针对自上次复位以来的累计值执行，而不是针对单个操作。 

第三个边缘情况是更新`c = 0`。```
a = [5]
h = 5

operation:
+0
```该值保持不变`5`，这是允许的，因为仅当值严格大于时才会发生崩溃`h`。 

正确的输出仍然存在`[5]`。 

## 方法

 最直接的模拟显式保留当前数组。 对于每一次操作，我们修改一个位置，然后检查是否有任何元素超出`h`。 如果发生崩溃，我们会恢复原始阵列。 

这是正确的，因为它遵循字面意思。 

问题是检测崩溃。 每次操作后我们都需要扫描所有`n`元素来查看某个值是否超过`h`。 高达`2·10^5`运营和`2·10^5`元素，这变成`O(nm)`在最坏的情况下。 

关键的观察结果是，在操作过程中只有一个位置发生变化。 

假设我们为每个索引存储自最近重置以来添加的总量。 让```
delta[i] = additions applied to position i since the last crash
```位置的当前值`i`是```
a[i] + delta[i]
```当一个操作添加`c`定位`b`, 仅有位置`b`变化。 其他所有位置都保持与之前相同的值。 

这意味着崩溃只能由更新的位置触发。 无需检查整个阵列。 

更新后`delta[b]`，我们简单地检查是否```
a[b] + delta[b] > h
```如果没有，则操作成功。 

如果它大于`h`，发生崩溃并且自上次重置以来所有累积的修改都会消失。 概念上全部`delta`值变为零。 

重置整个长度-`n`每次数组都会再次变得昂贵。 我们需要一种方法来在恒定时间内清除所有累积的更新。 

诀窍是将崩溃之间的更新视为属于“一代”。 每个位置都会记住其存储的增量上次更新的代。 当发生崩溃时，我们会增加生成计数器。 任何旧的增量都会自动变得无关紧要，因为它的生成不再与当前生成匹配。 

这是标准的延迟重置技术。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(纳米) | O(n) | 太慢了|
 | 最佳| O(n + m) | O(n) | 已接受 |

 ## 算法演练

 1.存储原始数组`a`。 
2. 创建数组`delta`长度`n`，最初全部为零。 
3. 创建数组`stamp`长度`n`，最初全部为零。 
4. 维护当前代号`cur`， 最初`1`。 
5. 对于一个操作`(b, c)`， 转变`b`从零开始的索引。 
6. 如果`stamp[b] != cur`，那么存储的 delta 属于老一代。 放`delta[b] = 0`和`stamp[b] = cur`。 
7. 添加`c`到`delta[b]`。 
8. 检查是否`a[b] + delta[b] > h`。 
9. 如果条件不成立，则继续下一步操作。 
10. 如果条件为真，则会发生崩溃。 增量`cur`一个。 这从逻辑上清除了所有累积的增量，因为每个现有的邮票现在都属于较老的一代。 
11. 全部操作结束后，重建最终的数组。 对于每个位置：

 - 如果`stamp[i] == cur`，其值为`a[i] + delta[i]`。 
- 否则，它的值只是`a[i]`。 

### 为什么它有效

 在任何时候，当前阵列与原始阵列的区别仅在于自最近一次崩溃以来执行的更新。 For every index,`delta[i]`准确存储这些幸存更新的总和。 

生成计数器保证早期崩溃的所有更新都被忽略。 增加生成相当于将每个增量设置为零，但不影响整个数组。 

由于一项操作仅修改一个位置，因此只有该位置可以新超出`h`。 检查`a[b] + delta[b]`足以判断是否发生崩溃。 该算法始终保持问题陈述中描述的准确状态，因此最终重建的数组是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n, m, h = map(int, input().split())
        a = list(map(int, input().split()))

        delta = [0] * n
        stamp = [0] * n
        cur = 1

        for _ in range(m):
            b, c = map(int, input().split())
            b -= 1

            if stamp[b] != cur:
                delta[b] = 0
                stamp[b] = cur

            delta[b] += c

            if a[b] + delta[b] > h:
                cur += 1

        ans = []
        for i in range(n):
            if stamp[i] == cur:
                ans.append(str(a[i] + delta[i]))
            else:
                ans.append(str(a[i]))

        out.append(" ".join(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```数组`a`永远不会改变，因为它代表每次崩溃都会重置的原始状态。 

这对`(delta, stamp)`仅存储当前一代的更新。 每当崩溃后触及索引时，就会通过检查标记来懒惰地丢弃其陈旧信息。 

最微妙的部分是碰撞处理。 当崩溃发生时，我们不会修改任何元素`delta`或者`stamp`。 我们只增加`cur`。 这是有效的，因为每个存储的更新都会立即成为老一代的一部分，并从那时起被忽略。 

另一个微妙之处是操作顺序。 我们首先应用更新，然后测试该值是否超过`h`。 这与执行操作后发生崩溃的语句相匹配。 

Python 整数具有任意精度，因此值大约可达`2·10^14`不会导致溢出问题。

 ## 边缘情况

 ### 崩溃必须重置为原始数组

 输入：```
1
2 2 5
1 1
1 3
1 3
```第一次操作后，数组是`[4,1]`。 

第二次操作后就变成了`[7,1]`，崩溃了。 

该算法递增生成计数器。 所有存储的更新都会过时，因此最终的数组将重构为：```
[1,1]
```这与所需的重置为原始行为相匹配。 

### 允许值等于 h

 输入：```
1
1 1 5
2
1 3
```更新后的值恰好变为`5`。 

该算法检查：```
2 + 3 > 5
```这是错误的。 

没有发生崩溃，答案是：```
5
```使用`>= h`会错误地触发重置。 

### 累积更新导致溢出

 输入：```
1
1 3 5
0
1 2
1 2
1 2
```值的顺序是：```
2
4
6
```第三次操作超过`h`，因此生成计数器前进并且所有累积的更新消失。 

重构后的数组为：```
0
```这证实了该算法跟踪自上次重置以来的总贡献，而不仅仅是最近的操作。
