 ## 解决方案
 ## 问题理解

 我们得到一排火柴盒，每个火柴盒包含一定数量的火柴。 匹配的总数可以被盒子的数量整除，因此存在一个目标配置，其中每个盒子最终都持有完全相同的数字。 

唯一允许的操作是将单个匹配项从一个框移动到其紧邻的框。 移动是本地的，因此将火柴从盒子 1 运输到盒子 5 需要多次移动，因为它必须经过中间盒子。 

任务是计算将初始分布转变为完美平衡分布所需的此类相邻移动的最小数量。 

关键限制是框的数量最多可以达到 50000 个，而值可以达到 10^9。 这立即排除了任何将单个比赛一场一场地移动的模拟。 即使单个匹配也可能需要 O(n) 步骤来重新定位，而对所有匹配天真地执行此操作将导致 O(nk) 行为，这远远超出了限制。 

隐藏的困难是动作不是独立的。 移动一场比赛会改变局部不平衡并影响未来的决策，因此必须仔细构建贪婪的局部平衡，以避免重复计算或遗漏间接流量。 

当尝试通过向右侧或左侧发送多余的内容而不跟踪累积流量来独立“修复”每个框时，会出现常见的失败情况。 例如，如果我们试图贪婪地将剩余推给邻居，我们可能会在同一运动通过线路传播时对它进行多次计数。 

失败的一个小例子：考虑输入`3`和`[1, 0, 5]`。 一种简单的方法可能会从最后一个框发送 2 个匹配到中间，然后从中间到第一个框发送 2 个匹配，但如果没有正确跟踪传播，则根据方向处理，同一单位移动的计数可能会不一致。 

正确的解决方案需要对不平衡流量有全局的看法，而不是局部修复。 

## 方法

 一个蛮力的想法是重复扫描数组，找到一个有盈余的盒子，然后将一场比赛逐步推向赤字。 每个这样的移动都被明确地模拟。 这是正确的，因为它确实遵循允许的操作，但速度太慢。 在最坏的情况下，一场比赛可能会移动 O(n) 距离，并且可能有 O(nk) 次这样的移动，根据分布导致二次或更差的行为。 

改进来自于我们注意到我们不需要模拟个别比赛。 重要的是有多少匹配项必须穿过相邻框之间的每个边界。 

如果我们查看索引 i 之前的框的前缀，它当前持有的匹配数与最终平衡状态下应持有的匹配数之间存在一些差异。 这个差异必须跨越 i 和 i+1 之间的界限。 这意味着前缀中的每一个不平衡都会直接转化为跨越该边缘所需的移动。 

因此，我们不是跟踪个别比赛，而是跟踪运行不平衡。 当我们从左向右移动时，我们会维护到目前为止累积的额外或缺失的比赛数量。 每个位置上这种不平衡的绝对值正是必须跨越该边界的匹配数。 

这将问题简化为单个线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 最坏情况 | O(nk) O(n) | 太慢了 |
 | 前缀不平衡跟踪 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 通过将总和除以 n 来计算每个框的目标匹配数。 这给出了每个位置的最终所需值。 
2.初始化两个变量：运行不平衡`carry`和一个答案累加器`moves`。 这`carry`表示有多少多余的匹配已从之前的盒子中传递但尚未吸收。 
3. 从左到右遍历每个框。 
4. 在每个框 i 处，通过添加当前框与目标的偏差来更新不平衡：`carry += a[i] - target`。 
5. 添加绝对值`carry`到答案。 这表示由于累积的不平衡，必须跨越框 i 和 i+1 之间的边界的匹配。 
6. 继续直到结束。 最终的答案是所有绝对不平衡的总和。 

关键的推理步骤是，一旦我们修复了一个前缀，任何剩余的不平衡都必须物理地通过边界到达下一段，并且每次这样的通过在每单位比赛中恰好花费一次移动。 

### 为什么它有效

 在每个位置 i，变量`carry`等于前缀中匹配的净剩余`[0..i]`与最终配置中应包含的前缀进行比较。 由于火柴只能跨越相邻边界，因此剩余的每个单位都必须在某个点跨越 i 处的边界。 对这些盈余的绝对值求和只会对每个交叉计数一次，因为每个不平衡都与流表示中的一个边界转换相关联。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    target = total // n
    
    carry = 0
    moves = 0
    
    for x in a:
        carry += x - target
        moves += abs(carry)
    
    print(moves)

if __name__ == "__main__":
    solve()
```其实现直接遵循前缀不平衡的思想。 目标计算一次。 该循环维持运行盈余或赤字。 绝对值累加是关键步骤，因为它计算必须穿过每个边界的流量。 

一个微妙的点是我们不重置`carry`添加到后`moves`。 进位代表通过数组传播的持续不平衡，因此重置它会破坏全局流结构。

 ## 边缘情况

 一种边缘情况是所有匹配项已经均匀分布。 该算法干净地处理了这个问题，因为`carry`始终保持为零，并且不添加绝对贡献。 

另一种情况是，不平衡在一侧严重累积，然后才得到解决。 例如：```
4
0 0 8 0
```利差变得越来越负，直到遇到盈余。 每个步骤都对答案做出了正确的贡献，因为每个边界都必须将赤字向前推进。 

最后一种情况是最小输入大小：```
1
k
```由于没有边界，因此不需要移动。 循环运行一次，但减去目标后进位立即为零，导致零移动。
