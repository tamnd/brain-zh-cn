 ## 解决方案
 ## 问题理解

 我们收到了一份时间表，描述了 Sagar 何时繁忙，我们需要确定 Jagjeet 所选择的时刻是否属于这些繁忙时段。 

萨加尔的忙碌模式开始于时间`a`。 此后，他的可用性以结构化方式交替：每个周期都基于`b`。 在每个周期中，有两个忙碌时刻：第一个是在周期开始时，第二个是一秒后。 具体来说，繁忙时间成对出现：`a, a+1`， 然后`a+b, a+b+1`， 然后`a+2b, a+2b+1`， 等等。 

所以任务很简单：对于每个查询，检查给定时间是否`c`等于这些繁忙时间戳中的任何一个。 

输入规模较小，最多有 1000 个测试用例，值最多 10^9。 这立即排除了随着时间的推移进行任何模拟或时间表的迭代扩展。 任何正确的解决方案都必须在每个测试用例的恒定时间内决定成员资格。 

一个常见的错误是将模式解释为连续间隔，例如认为 Sagar 正忙于处理诸如`[a, a+1]`,`[a+b, a+b+1]`等等，但随后不小心将它们视为重叠或延伸的间隔。 由于间隔是孤立且不重叠的（因为`b ≥ 1`），重叠仅发生在`b = 1`，在这种情况下，连续的对合并成连续的繁忙段。 即使在这种情况下，直接成员资格检查仍然有效，但粗心的区间合并逻辑可能会破坏边缘处理。 

另一个微妙的边缘情况是当`c < a`。 在这种情况下，萨加尔根本没有开始忙碌，所以答案一定是“否”。 同样，当`b = 1`，繁忙时间变为从`a`， 自从`(a, a+1), (a+1, a+2), ...`涵盖所有整数`a`向前。 

## 方法

 暴力方法可以通过生成对来模拟 Sagar 的繁忙时间`(a + k*b, a + k*b + 1)`为了增加`k`，一旦超过就停止`c`。 对于每个生成的对，我们检查是否`c`匹配任一端点。 这是正确的，因为它直接构造了所描述的模式。 

然而，当`c`相对于`a`和`b`。 在最坏的情况下，如果`b = 1`，迭代次数线性增长至`c - a`，可以大到 10^9。 即使当`b`更大时，我们仍然需要在多个测试用例中进行多次迭代。 

关键的观察是该结构是完全周期性的，我们不需要枚举它。 相反，我们可以确定是否`c`与循环索引和偏移量对齐。 

对于给定的时间`c`，如果是繁忙时间，则必须满足两个条件之一：

 首先，这可能是一个周期的开始：`c = a + k*b`对于某个整数`k ≥ 0`。 这相当于`(c - a) % b == 0`。 

其次，这可能是一个周期中的第二个忙碌时刻：`c = a + k*b + 1`。 这相当于`(c - a - 1) % b == 0`。 

这两个条件也必须满足`c ≥ a`，因为繁忙时间永远不会发生在起点之前。 

这将问题减少到每个测试用例的恒定时间算术检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟 | 每次测试 O((c−a)/b) | O(1) | O(1) | 太慢了|
 | 模算术检查 | 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例并应用算术检查来确定繁忙日程中的成员资格。 

1. 读取数值`a`,`b`， 和`c`对于当前的测试用例。 这些定义了起点、周期长度和查询时间。 
2.如果`c < a`，立即断定Sagar此时不忙`c`。 这是根据定义得出的，因为时间表仅开始于`a`。 
3. 检查是否`c`通过测试是否匹配某个周期中的第一个繁忙位置`(c - a) % b == 0`。 如果这成立，那么`c`完全对齐`a + k*b`对于某个整数`k`。 
4. 如果前面的条件不成立，请检查是否`c`通过测试是否匹配循环中的第二个繁忙位置`(c - a - 1) % b == 0`。 这对应于`a + k*b + 1`。 
5. 如果任一条件为真，则输出“YES”。 否则输出“NO”。 

### 为什么它有效

 每个忙碌时间都必须恰好属于两个算术级数之一：一个从`a`有步骤`b`，并且一个开始于`a+1`用同样的步骤`b`。 这两个序列完整地描述了时间表，并且它们不会产生误报，因为每个有效时间必须映射到唯一的循环索引`k`。 模条件确保只有通过整数步长才能到达的时间`a`或者`a+1`增量为`b`已接受，与结构完全匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    for _ in range(n):
        a, b, c = map(int, input().split())

        if c < a:
            print("NO")
            continue

        if (c - a) % b == 0 or (c - a - 1) % b == 0:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```代码直接遵循导出的条件。 第一个守卫处理调度开始之前查询的琐碎排除。 两个模检查完全对应于定义繁忙模式的两个算术级数。 不需要循环，因此每个测试用例都在恒定时间内处理。 

一个微妙的实现细节是`(c - a - 1)`当`c = a`，但是 Python 的模数在这种情况下可以正确处理负操作数，并且前面的条件已经确保了正确性。 早期的`c < a`检查可以防止不必要的歧义。

 ## 边缘情况

 一个重要的边缘情况是当`c = a`。 在这种情况下，答案必须始终是“是”，因为第一个忙碌时刻正好开始于`a`。 该算法可以正确处理这个问题，因为`(c - a) % b = 0`评估为`0 % b = 0`，触发阳性结果。 

另一种情况是当`b = 1`。 忙碌的时光变得`(a, a+1), (a+1, a+2), ...`，有效覆盖来自的每个整数`a`向前。 支票`(c - a) % 1 == 0`对于`c ≥ a`，因此算法对于所有此类情况正确返回“YES”，而`c < a`已经被排除了。 

最后，当`c < a`，由于负算术，两个模块化检查都会产生误导性的值，但早期的防护完全阻止了这种情况。 例如，如果`a = 10, c = 3`， 然后`(c - a) = -7`模运算仍然可以在 Python 中返回有效的残数，但它们是无关紧要的，因为时间表尚未开始，因此正确的输出始终是“NO”。
