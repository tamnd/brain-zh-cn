 ## 解决方案
 ## 问题理解

 我们为每个测试用例提供一个字符串，并且需要找到包含特定字母多重集的连续子字符串。 所需的字母对应于单词“hardwork”，但不符合该单词本身的常见频率模式。 相反，我们需要确保子字符串至少包含字母 h、a、d、w、o、k 中的每一个，并且重要的是 r 出现两次。 

所以任务不是匹配一个单词，而是找到字符串中满足固定频率要求的最小窗口：h×1、a×1、d×1、w×1、o×1、k×1、r×2。 

每个测试的输出是此类子字符串的最小长度，如果没有子字符串可以满足这些约束，则输出 -1。 

每次测试的输入大小最多可达 10^5 个字符，最多可进行 1000 次测试。 这立即意味着任何显式检查所有子字符串的解决方案都将太慢。 每次测试的三次或二次扫描将远远超出可接受的限制，因为最坏情况下测试的输入大小可能达到 10^8 个字符。 

每个测试都需要线性或近线性方法，这强烈建议在字符串上使用滑动窗口策略。 

有一些微妙的失败案例值得牢记。 一种情况是字符串包含所有必需的字母，但 r 出现的次数不够。 例如，“hardwok”完全缺少 r，因此即使出现了大多数字母，答案也是 -1。 另一种情况是当r在整个字符串中只出现一次时，例如“harrdwok”，仍然失败。 一个更微妙的问题是，可能存在多个有效窗口，并且算法必须正确跟踪重叠有效段之间的最小长度，而不是在第一个有效段处停止。 

## 方法

 暴力方法会考虑每个可能的子字符串并检查它是否满足所需的计数。 对于长度为 n 的字符串，有 O(n²) 个子字符串，如果我们维护频率表，则每次检查的成本为 O(1)，如果重新计算，则每次检查的成本为 O(n)。 即使在最好的设置中，这也会导致每次测试的时间复杂度为 O(n²)，这在 n = 10^5 时是完全不可行的。 

关键的观察结果是，该问题是一个经典的固定要求最小窗口问题。 我们不是在寻找模式，而是在寻找满足频率约束的最小间隔。 这种结构允许两指针滑动窗口：我们扩展右边界直到窗口变得有效，然后收缩左边界，同时保持有效性以最小化长度。 

关键的见解是，有效性在扩展方面是单调的：一旦窗口包含足够的字符，添加更多字符就不会破坏有效性。 这种单调性允许单次传递，其中每个字符最多添加和删除一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 滑动窗| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们为目标字母确定所需的频率图，然后用两个指针扫描字符串。

1. 初始化当前窗口的频率计数器和满足所需条件数量的计数器。 我们还定义了目标要求：h、a、d、w、o、k 必须至少出现一次，r 必须至少出现两次。 
2. 将右侧指针移过字符串，将每个字符添加到当前频率图中。 每次更新都可能增加满足的要求数量。 例如，只有达到阈值 2 时，r 的第二次出现才会计数。 
3. 每次扩展后，检查当前窗口是否满足所有要求。 此检查是恒定时间，因为我们增量跟踪满意度而不是重新计算频率。 
4. 当窗口变得有效时，尝试将其从左侧缩小。 我们在窗口保持有效的情况下一一删除字符，每当找到更小的有效窗口时就更新答案。 此步骤确保我们不仅找到有效窗口，而且找到以当前右指针结尾的最小窗口。 
5. 继续扩展右指针直到字符串末尾，始终保持不变式：任何时候窗口有效，它都会从左侧局部最小化。 
6. 如果未找到有效窗口，则返回 -1。 

关键的微妙之处在于处理 r 的要求两次。 r 不是同等对待所有字母，而是仅当其计数达到至少 2 时才有助于有效性，而所有其他字符需要至少出现 1 次。 

### 为什么它有效

 在右指针的每个位置，算法都会维护尽可能小的左边界，以使窗口有效。 由于右指针仅向前移动，因此当右指针到达其结束位置时，将发现在当前右指针处或之前开始的任何未来有效窗口。 左指针仅向前移动，因此不会跳过候选窗口。 这保证了每个有效窗口以其最小形式被恰好考虑一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

REQ = {'h': 1, 'a': 1, 'd': 1, 'w': 1, 'o': 1, 'k': 1, 'r': 2}

def is_valid(cnt):
    return (
        cnt['h'] >= 1 and
        cnt['a'] >= 1 and
        cnt['d'] >= 1 and
        cnt['w'] >= 1 and
        cnt['o'] >= 1 and
        cnt['k'] >= 1 and
        cnt['r'] >= 2
    )

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    cnt = {c: 0 for c in REQ}
    left = 0
    best = float('inf')

    for right in range(n):
        if s[right] in cnt:
            cnt[s[right]] += 1

        while left <= right and is_valid(cnt):
            best = min(best, right - left + 1)
            if s[left] in cnt:
                cnt[s[left]] -= 1
            left += 1

    print(-1 if best == float('inf') else best)
```该代码使用了直接滑动窗口。 字典`cnt`仅跟踪对有效性重要的字符，从而保持更新时间恒定。 功能`is_valid`检查要求，但由于字母表很小且固定，因此每次检查仍然是 O(1)。 

内部 while 循环是收缩阶段：它反复尝试丢弃左侧的字符，同时保持有效性。 一旦有效性被打破，循环就会停止，右指针继续扩展。 

一个微妙的问题是我们只追踪七个相关的角色。 其他的都被忽略，因为它们不能影响是否满足要求，只有窗口长度。

 ## 边缘情况

 一种重要的边缘情况是所有字符都出现但第二个 r 被延迟到最后。 在像这样的字符串中`hardwokr`，第一个有效窗口仅在第二个 r 出现的最终位置才成为可能。 在尝试任何收缩之前，该算法会正确扩展直到该点，因此不会做出过早的决定。 

另一种情况是多个 r 字符提前聚集。 在`hharrdwok`，算法很快满足 r ≥ 2，但仍然无法收缩，直到所有其他所需字符出现。 窗口多次扩展和收缩，但由于 left 仅向前移动，因此每个中间无效状态都会得到正确处理，而无需重新访问位置。 

第三种情况是字符串主要由不相关的字符组成，并嵌入了单个有效簇。 由于不相关的字符在计数器中被忽略，因此它们只会增加窗口长度。 收缩步骤保证一旦完全包含簇，算法就会消除周围的噪声并隔离最小的有效片段。
