 ## 解决方案
 ## 问题理解

 每个学生的成绩都有两个组成部分：固定的考试分数和可控的连续评估分数。 对于学生$i$，当前总数为$x_i + y_i$， 在哪里$x_i$课程作业分数上限是$a$， 和$y_i$考试分数上限是$b$。 如果学生的总分至少达到$c$，否则他们会失败。 

允许教师应用单个全局运算：添加一个非负整数$d$每个学生的课程成绩。 在此增加之后，任何课程作业分数超过$a$被剪回$a$。 考试成绩保持不变。 目标是计算执行此操作后有多少学生从不及格转变为通过。 

约束条件$n \le 1000$意味着独立检查每个学生的固定$d$是微不足道的，因此任何最多线性的解决方案$n$每个候选操作就足够了。 取值范围都很小，特别是$d \le 100$，这表明对所有可能的情况进行暴力破解$d$是完全可行的。 

一个微妙的细节是课程作业分数的剪裁。 如果$x_i + d > a$，贡献正好变成$a$， 不是$x_i + d$。 这会在最终得分中产生分段行为，这是幼稚推理中错误的主要来源。 

一个常见的失败案例是忽略上限效应。 For example, if$a = 40$,$x_i = 35$， 和$d = 10$，课程作业贡献不是 45 而是 40。任何直接添加的解决方案$d$如果不应用上限，就会高估分数，并将边缘学生错误地划分为及格。 

另一个陷阱是误解计算的内容。 我们不计算所有手术后通过的学生，只计算那些最初不及格并因手术而通过的学生。 

## 方法

 蛮力的想法很简单：尝试每一个可能的值$d$从 0 到 100。对于每个$d$，重新计算每个学生调整后的课程作业分数，计算他们的总分，并检查他们是否通过。 我们还需要基线：在进行任何修改之前哪些学生会失败。 

这是有效的，因为范围$d$很小。 最坏情况的计算是$101 \times 1000$学生，我们为每个学生做持续的工作，所以$10^5$操作总计。 这是舒适的小。 

关键的简化是学生之间不存在交互。 每个学生的成绩只取决于他们自己$(x_i, y_i)$和全局参数$d$。 这种独立性消除了对组合或子集优化的任何需要。 我们只模拟少量的全局状态。 

我们为每个学生计算两个状态$d$：原始通过/失败状态，以及应用上限调整增加后的新通过/失败状态。 我们计算从不及格到通过的转变。

 | 暴力破解结束$d$|$O(n \cdot 101)$|$O(1)$| 已接受 |

 ## 算法演练

 1.读取所有输入值，包括$n, a, b, c$、学生名单、全局增量$d$。 
2. 对于每个学生，计算他们当前是否通过：检查是否$x_i + y_i \ge c$。 隐式存储此布尔值或计数结构。 
3.对于给定的$d$，将每个学生的新课程成绩计算为$\min(a, x_i + d)$。 
4. 将新的总分计算为$\min(a, x_i + d) + y_i$。 
5. 检查学生现在是否通过。 
6. 计算初始状态未通过但新状态通过的学生。 
7. 输出该计数。 

每个学生都是独立评估的，因此我们永远不需要在最终计数之外维护全局状态。 

### 为什么它有效

 适用于所有学生的操作是统一的，通过条件纯粹是每个学生的累加。 这使得系统可分为独立的每个学生转换。 由于课程作业调整对于固定的$d$，每个学生只有一个状态转换结果。 因此，计算改进相当于对所有学生的独立布尔事件求和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a, b, c = map(int, input().split())
    
    students = []
    for _ in range(n):
        x, y = map(int, input().split())
        students.append((x, y))
    
    d = int(input())
    
    improved = 0
    
    for x, y in students:
        before = (x + y >= c)
        
        x2 = x + d
        if x2 > a:
            x2 = a
        
        after = (x2 + y >= c)
        
        if not before and after:
            improved += 1
    
    print(improved)

if __name__ == "__main__":
    solve()
```该解决方案直接遵循每个学生的模拟。 唯一重要的步骤是正确应用上限：修改后的课程作业是`min(a, x + d)`，必须在与考试成绩求和之前计算。 

“之前”标志确保我们只计算最初不及格的学生。 如果没有这个，结果将错误地包括已经通过和仍然通过的学生。

 ## 边缘情况

 一个关键的边缘情况是，学生在操作前的成绩略低于及格线，而在剪裁后刚刚达到及格线。 

输入：```
n = 1
a = 40, b = 100, c = 80
x = 35, y = 40
d = 10
```前：$35 + 40 = 75$，失败。 

之后：课程作业变成$\min(40, 45) = 40$，所以总计是$40 + 40 = 80$，路过。 

该算法计算：

 - 之前 = false
 - x2 = 40（由于上限）
 - 之后 = true

 所以它正确地计算了这个学生。 

一个对比的情况是忽略上限：

 如果有人错误地使用$x + d = 45$，则总计变为$85$，仍然通过，所以这种情况不会破坏正确性。 真正的危险出现的时候$x$接近于$a$上限可以防止预期收益将学生推向门槛； 天真的加法会高估这些场景中的改进。
