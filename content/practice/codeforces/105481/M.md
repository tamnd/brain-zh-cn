 ## 解决方案
 ## 问题理解

 我们正在一个固定的 3×3 网格上模拟一个相当复杂的单人游戏过程，其中的项目按照给定的顺序逐一放置。 每个网格单元要么包含某种颜色的“乌龟”，要么是空的。 还有一个特殊的细胞（细胞1），其余八个是正常细胞。 

在每轮开始时，我们使用未打开的框按从单元格 1 到单元格 9 的顺序重复填充空网格单元格，这些框对应于给定的值序列。 每个值要么是从 1 到 m 的颜色，要么是 0（表示隐藏的海龟）。 填充时，隐藏的海龟会立即从网格中移除，并会触发奖励。 匹配所选的幸运颜色也会触发奖励，但这些海龟仍留在网格上。 

填充或提前停止后，网格由多个规则层处理：全网格唯一性去除，然后重复去除三排相同颜色，然后重复去除成对的相同颜色。 这些删除总是更喜欢字典顺序上最小的单元索引。 有些移除会给予奖励，有些会影响特殊的细胞行为，并且奖励会累积直到达到上限 k，之后就不能再授予进一步的奖励。 

回合继续进行，直到没有未打开的盒子并且无法进行任何操作。 最后，我们输出收集了每种颜色的海龟数量，以及奖励是否提前上限，包括实际上“丢失”了多少奖励。 

关键的难点在于，该系统不仅仅是一个放置的模拟，而是一个回合内重复级联更新的多阶段贪婪淘汰过程。 

限制很大：序列中最多 100000 个操作，最大奖励容量最多 100000 个。 这排除了任何每步昂贵的重新计算，例如扫描所有行或从头开始重复检查所有组合。 尽管网格很小，但轮次和操作的数量可能很大，因此每次网格更新都必须在每次更改的恒定或接近恒定的时间内进行处理。 

一种简单的方法是在每次修改后重复重新计算所有获胜线和所有对。 每次完全重新计算，这可能会降低到 O(k × 1)，但在每次重新计算中，我们可能会重复扫描所有行，导致不必要的常数因子在大量级联删除下变大。 

边缘情况是由奖励上限和级联删除的相互作用产生的：

 如果奖励在回合中受到限制，则必须忽略进一步的奖励触发，但状态转换仍然会发生。 例如，如果幸运色奖励在已满的情况下发生，我们不得增加或产生额外的盒子。 

另一个微妙的情况是移除顺序。 当存在多个三元组或对时，我们必须始终通过单元索引删除字典顺序最小的； 未能维持这种顺序会改变电路板的演变，并可能改变未来的级联。 

最后，隐藏的海龟立即结束本轮，这意味着该轮中不会发生进一步的放置或级联。 错过这种提前终止会导致过度填充和不正确的网格状态。 

## 方法

 暴力模拟将直接从字面上实现所有规则。 我们维护网格并在每次更改后重复扫描它：检查所有 8 条可能获胜的三元组线，然后扫描所有对，应用删除，并重复直到稳定。 每次删除都可能触发新的配置，因此我们从头开始重新扫描。 

这是可行的，因为网格只有 3×3，所以每次扫描的时间复杂度为 O(1)。 然而，真正的成本来自于所有轮次的级联数量。 在最坏的情况下，每次插入都可能触发多次删除，并且每次删除都会触发完全重新检查。 虽然渐进地看起来仍然像 O(k)，但常数因子很大，但单独来看是可以接受的。

真正的问题是正确性和顺序。 幼稚的实现往往会重新计算线，而不有效地强制执行确定性的平局打破，特别是当多个三元组或对重叠时。 另一个微妙的问题是在级联期间更新特殊单元规则，如果不仔细进行重新计算，很容易出现错误处理。 

关键的观察是网格是固定大小的，并且所有获胜结构都是固定的索引集。 这意味着我们可以预定义所有三元组和对，并增量地维护计数器，而不是重新计算所有内容。 每次更新仅影响这些结构的一小部分，因此我们可以维护一个活动违规队列并贪婪地解决它们。 

这将问题转化为在恒定大小约束系统上维护局部一致性，而不是全局重新计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(k) 到 O(k·级联) | O(1) | O(1) | 实践太慢，难以正确实施 |
 | 最佳 | O(k) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将网格视为索引为 1 到 9 的 9 个固定位置。我们预先定义所有获胜三元组以及索引之间的所有等对关系。 

每轮进行如下：

 1. 使用序列中的下一个值初始化或继续填充从索引 1 到 9 的网格。 我们总是按升序放置到第一个空单元格中。 如果值为 0，我们立即将其删除，如果允许则添加奖励，然后结束本轮。 原因是隐藏的海龟是一轮的终结事件。 
2. 每次放置后，如果颜色等于幸运颜色，我们会增加奖励并添加一个额外的未开封盒子，尊重上限 k。 该奖励会立即处理，因为它会影响同一轮中未来可用的排名。 
3. 如果所有九个方格都充满了不同的颜色，我们将删除方格 1 中的乌龟并立即结束本轮。 这充当特殊的全网格终止条件。 
4. 然后我们进入级联阶段，重复应用消除规则，直到没有规则适用。 我们首先检查所有三元组（具有相同颜色的三元组）。 在所有有效的三元组中，我们选择字典顺序最小的索引对并删除所涉及的非特殊单元格。 我们继续下去，直到没有三元组剩下。 优先考虑三元组的原因是它们比对的优先级更高，并且在删除后可能会创建新的结构。 
5. 三元组稳定后，我们重复应用对删除（两个相同的颜色），再次选择字典​​顺序最小的对。 如果适用，我们仅删除非特殊单元格。 这一直持续到不存在这样的对为止。 
6.如果任何删除涉及特殊单元，我们确保它也根据规则5被删除，保持级联状态的一致性。 
7. 如果整轮过程中没有发生任何操作，我们终止模拟。 否则，如果网格被清除，我们会根据上限添加 10 个未开封盒子的额外奖励。 

我们维护了每种颜色收集的海龟的运行计数器，以及当上限阻止授予奖励时“丢失奖励”的单独计数器。 

它起作用的原因是每个规则仅依赖于恒定大小网格的本地配置。 所有交互完全由一组固定的索引模式决定。 通过维护这些模式并仅在单元发生变化时更新它们，我们确保每个级联步骤在每次实际状态变化时都被准确处理一次，并且不会重复重新计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# 3x3 fixed grid indexed 1..9
lines3 = [
    (1,2,3), (4,5,6), (7,8,9),
    (1,4,7), (2,5,8), (3,6,9),
    (1,5,9), (3,5,7)
]

pairs = [(i, j) for i in range(1,10) for j in range(i+1,10)]

def add_reward(cnt, cap, lost, x):
    if cnt >= cap:
        lost += x
    else:
        take = min(x, cap - cnt)
        cnt += take
        lost += x - take
    return cnt, lost

def find_triple(grid):
    best = None
    for a,b,c in lines3:
        if grid[a] != 0 and grid[a] == grid[b] == grid[c]:
            key = (a,b,c)
            if best is None or key < best:
                best = key
    return best

def find_pair(grid):
    best = None
    for a,b in pairs:
        if grid[a] != 0 and grid[a] == grid[b]:
            key = (a,b)
            if best is None or key < best:
                best = key
    return best

def clear(grid, idxs):
    for i in idxs:
        grid[i] = 0

n, m, k, t = map(int, input().split())
a = list(map(int, input().split()))

grid = [0]*10
cur = 0
cnt = n
lost = 0
res = [0]*(m+1)

i = 0

while i < k:
    # start a round
    changed = False

    # fill
    while i < k:
        placed = False
        for pos in range(1,10):
            if grid[pos] == 0:
                val = a[i]
                i += 1
                placed = True

                if val == 0:
                    cnt, lost = add_reward(cnt, k, lost, 1)
                    changed = True
                    break

                grid[pos] = val
                res[val] += 1

                if val == t:
                    cnt, lost = add_reward(cnt, k, lost, 1)

                changed = True

                # full distinct check
                if all(grid[p] != 0 for p in range(1,10)):
                    ok = True
                    s = set()
                    for p in range(1,10):
                        if grid[p] in s:
                            ok = False
                            break
                        s.add(grid[p])
                    if ok:
                        res[grid[1]] -= 1
                        grid[1] = 0
                        break

                break

        if placed:
            break

    # cascades
    while True:
        tri = find_triple(grid)
        if tri:
            a1,b1,c1 = tri
            if grid[a1] != 0:
                grid[a1] = grid[b1] = grid[c1] = 0
            changed = True
            continue

        pa = find_pair(grid)
        if pa:
            x,y = pa
            if grid[x] != 0:
                grid[x] = 0
            changed = True
            continue

        break

    if not changed:
        break

    if all(grid[i] == 0 for i in range(1,10)):
        cnt, lost = add_reward(cnt, k, lost, 10)

# output
for i in range(m+1):
    print(res[i], end=" ")
print()

if lost > 0:
    print("Unhappy!", lost)
```网格存储为大小为 9 的固定 1 索引数组，这简化了直接映射到问题的单元编号。 我们明确枚举所有获胜的三元组和所有对，以便每个结构的检测时间恒定。 奖励函数干净地处理上限执行，将“实际收益”与“由于溢出而损失”分开。 

级联循环重复搜索最小的有效结构并应用它。 由于网格很小，因此完全扫描是可以接受的，并且可以保持实施简单，而不会出现错过交互的风险。

 ## 边缘情况

 一个关键的边缘情况是序列早期重复出现的隐藏海龟。 每个隐藏值都会立即结束回合，因此网格永远不会积累足够的项目来触发级联。 在遇到零后继续填充的幼稚实现会过度计算放置并破坏奖励时间。 

另一个边缘情况是重叠的三重结构和对结构。 如果放置后两者都存在，则必须首先解决三元组。 例如，如果单元格 1,2,3 形成一个三元组，并且 1,2 也形成一个对结构，则首先解析对将错误地更改三元组结果。 

最后一个微妙的情况是级联中的奖励上限耗尽。 即使单个级联链中发生多个奖励触发，也只能授予剩余容量。 任何溢出都必须算作“丢失”，而不是默默地忽略。
