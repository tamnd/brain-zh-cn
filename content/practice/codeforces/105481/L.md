 ## 解决方案
 ## 问题理解

 我们正在考虑修改日历，其中每年被分类为训练年或休息年。 从 2024 年开始，角色在每个训练年中只获得一个单位的进步，而休息年则不会做出任何贡献。 每个查询的任务是确定获得第 k 个进度单位的时刻对应于哪个日历年。 

困难完全在于如何定义“休息年”。 如果某一年满足取决于 100 次方的广义闰年规则，则该年份被视为休息年。与通常的公历结构不同，整除性条件引入了例外层次结构：需要能被 4 整除，但一年是否被排除或包含取决于它包含多少个 100 的尾随因子，并在更深尺度（如 100、10000、1000000 等）上交替约束。 

因此，真正的计算任务不是多年来的模拟，而是计算到给定年份发生了多少个训练年，然后反转该计数以找到何时达到 k。 

输入大小最多可达 10^5 个查询，k 可以大到 10^18。 这立即排除了任何逐年迭代的方法。 即使是每年的对数模拟也是不可能的； 相反，我们需要一个对年的大前缀进行直接计数的函数，以及一种有效地反转它的方法，最自然地通过二分搜索。 

一个微妙的边缘情况来自于起点。 进度从 2024 年开始累积，因此我们不是从第一年开始计数。因此，必须移动任何前缀计数函数，以便我们正确减去 2023 年之前的所有内容。未能对齐此基线会导致最终答案中出现相差一的错误。 

## 方法

 直接模拟将从 2024 年开始迭代，检查每年是否是训练年，并递减 k 直到达到零。 这在概念上很简单，因为规则是确定性的，但它是完全不可行的。 由于 k 可以是 10^18，并且每个步骤对应于一年，因此这种方法每个查询最多需要 10^18 次迭代。 

问题的结构提出了一种不同的观点：我们不是逐年行走，而是询问到给定的 x 年为止存在多少个训练年数。 如果我们可以快速计算该值，那么我们可以二分搜索最小的 x，使得从 2024 年到 x 的训练年数至少为 k。 

因此，主要困难是计算扩展闰规则下直至 x 的休息年数。 尽管定义看起来很复杂，但剩余年份的集合是基于 100 次幂的不相交算术条件的并集。每个级别都提供一组可被 4·100^p 整除但不能被 100^{p+1} 整除的数字。 这些集合不重叠，这使我们能够独立地对它们进行计数。 

对于每个 p，直到 x 的此类年份的计数就是 Floor(x / (4·100^p)) 减去 Floor(x / (4·100^{p+1}))。 对所有相关 p 进行求和，得出直至 x 的剩余年数总数。 由于 100^p 增长得非常快，因此即使 x 达到 10^18，也只需要少量项。 

一旦我们能够以 100 的幂的对数时间来评估 x 的训练年数，我们就可以对每个查询的答案进行二分搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟 | 每次查询 O(k) | O(1) | O(1) | 太慢了 |
 | 前缀计数+二分查找| O(log X · log k) | O(log X · log k) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将问题重新表述为找到最小年份 x ≥ 2024，使得从 2024 年到 x 的训练年数等于 k。 

### 第 1 步：定义前缀函数

 我们定义一个函数rest(x)来计算[1,x]中存在多少个休息年。 直到 x 的训练年数为 x - 休息(x)。

最终答案需要将其调整为从 2024 年开始的范围，因此我们稍后将减去直到 2023 年的前缀。 

### 步骤 2：按级别计算休息年数

 我们观察到剩余年份由索引 p 划分。 对于每个 p ≥ 0，我们认为年份可以被 4·100^p 整除，但不能被 100^{p+1} 整除。 这些集合在不同的 p 值上是不相交的。 

因此，对于固定的 x，级别 p 的贡献为：

 地板(x / (4·100^p)) − 地板(x / (4·100^{p+1}))

 我们对所有 p 求和，直到 4·100^p 超过 x。 

### 步骤 3：计算训练前缀

 我们计算：

 训练 (x) = x − 休息 (x)

 这给出了从第 1 年到第 x 年的训练年数。 

### 第 4 步：转至 2024 年开始

 让：

 基地=火车（2023）

 那么从 2024 年到 x 的训练年份是：

 训练（x） - 基地

 我们需要：

 train(x) − 基数 ≥ k

 ### 步骤 5：二分查找

 我们二分查找最小的 x 以使条件成立。 搜索范围可以安全地扩展到 10^18 + 2024，因为 k ≤ 10^18 并且训练年限几乎线性增加。 

每次检查都需要计算rest(x)，由于100^p的指数增长，计算速度很快。 

### 为什么它有效

 正确性依赖于两个结构事实。 首先，剩余年份的分类分解为由 p 索引的不相交集合，因此没有年份被重复计算。 其次，每个 p 的贡献迅速下降，因为 100^p 呈指数增长，确保只有 O(log_{100} x) 项是相关的。 这使得前缀函数定义明确且可有效计算，并且二分搜索有效，因为 train(x) 在 x 中单调递增。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def rest_upto(x: int) -> int:
    res = 0
    p = 0
    while True:
        base = 4 * (100 ** p)
        if base > x:
            break
        next_base = base * 100
        res += x // base - x // next_base
        p += 1
    return res

def train_upto(x: int) -> int:
    return x - rest_upto(x)

T = int(input())

BASE = train_upto(2023)

def solve_one(k: int) -> int:
    lo, hi = 2024, 10**19
    while lo < hi:
        mid = (lo + hi) // 2
        if train_upto(mid) - BASE >= k:
            hi = mid
        else:
            lo = mid + 1
    return lo

out = []
for _ in range(T):
    k = int(input())
    out.append(str(solve_one(k)))

print("\n".join(out))
```该实现是围绕两个抽象层构建的。 功能`rest_upto(x)`直接对 p 层上的分解进行编码，迭代直到基项超过 x。 每次迭代都会提供可被 4·100^p 整除的年数，但不能被下一个级别整除。 

功能`train_upto(x)`通过减法将其转换为培训年数。 

每个查询都会执行二分搜索，但由于 100^p 序列增长极快，昂贵的部分仍然是对数的。 

一个微妙的实现细节是预计算`BASE = train_upto(2023)`。 这可确保我们从 2024 年开始正确调整计数窗口。错过此转变会导致答案始终偏离恒定量。

 ## 边缘情况

 一个关键的边缘情况是 2024 年起点的对齐。如果我们错误地假设计数从第一年开始，则每个结果都会发生变化。 例如，如果 2024 年是第一个训练年，则 k=1 必须返回 2024。任何忘记减去 train(2023) 的实现都会错误地返回 1 或接近开始的年份。 

另一个边缘情况是休息年份的稀疏结构。 由于它们仅发生在非常特定的整除模式中，因此早期测试可能会误导性地表明该序列的行为类似于标准闰年。 这可以隐藏索引错误，直到非常大的 k 值暴露出不正确的增长率。
