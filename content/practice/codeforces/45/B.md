 ## 解决方案
 ## 问题理解

 每个学生都指向另一名学生，即他们听到新闻时打电话给的那个人。 这创建了一个有向函数图，每个节点的出度恰好为一。 

当天`i`，一名学生开始以初始力量传播一条消息`b[i]`。 消息每转发一次，强度就会减少一分。 一旦强度为零，转发就会停止。 学生可能会在同一天以不同的强度多次收到相同的新闻，因为周期是允许的。 

我们没有被问到学生总共听到新闻多少次。 我们只关心每个学生第一天得知任何消息。 对于每一天，我们必须输出当天有多少学生第一次被告知。 

起始学生没有直接给出。 反而，$$a_i = ((v_i + res_{i-1}) \bmod n) + 1$$在哪里`res[i-1]`是前一天的答案。 

图表大小和天数均达到`10^5`。 直接模拟每个电话是不可能的，因为`b[i]`也可以大到`10^7`。 如果简单地实现，即使是单个查询也可能需要遍历数百万条边。 

二次或偶数`O(n * sqrt(n))`在 2 秒限制内接近是危险的。 目标总体复杂度接近线性。 

棘手的部分是路径可以进入循环。 如果我们只是步行`b[i]`每天，我们都会重复访问相同的顶点。 另一个微妙的问题是，一旦学生在早些时候已经听到了消息，就不能再将其计算在内。 

考虑这个例子：```
3 1
2 3 1
1
10
```该图为一个周期：`1 -> 2 -> 3 -> 1`。 

消息在概念上永远循环，但强度每一步都会减弱。 有实力`10`，每个学生都听过很多次。 正确答案是：```
3
```如果实施时不小心计算每次访问而不是首次发现，则会产生更大的值。 

另一个危险的情况是当起始学生已经提前得到通知时：```
3 2
2 3 1
1 1
2 2
```第一天告知学生`2`和`3`开始于`2`。 

第二天又从`2`，但没有人是新的了。 正确的输出是：```
2
0
```如果我们忘记在几天内保持全局“已通知”状态，我们就会错误地计算重复的发现。 

当出现另一种微妙的情况时`b[i]`超过不同可到达顶点的数量：```
4 1
2 3 4 2
1
100
```可达集来自`2`只是`{2,3,4}`因为图最终会在这些节点内循环。 答案依然是：```
3
```幼稚的实现可能会浪费大量时间重复遍历同一周期。 

## 方法

 蛮力方法完全遵循所描述的过程。 

每天：

 1. 计算起始学生`a[i]`。 
2. 沿着传出边缘走到`b[i]`次。 
3. 如果每位访问的学生是第一次听到任何消息，请将其标记为知情。 

这个模拟是正确的，因为新闻传播实际上是一段步行路程`b[i]`在函数图中。 

问题在于复杂性。 在最坏的情况下，`b[i] = 10^7`和`m = 10^5`。 这意味着最多`10^12`边缘遍历，远远超出了可行的限制。 

关键的观察是每个学生只重要一次。 学生获悉情况后，以后对该学生的访问将不会再对答案有所帮助。 

这彻底改变了问题。 我们不需要模拟每次传输，只需有效地跳过已知的学生即可。 

假设我们沿着传播路径行走。 每当我们遇到一个已经知道的学生时，处理该顶点是没有用的。 我们想要一个能够快速跳转到下一个仍不知情的顶点的结构。 

这正是不相交集并集所能做到的。 

我们维护类似 DSU 的“下一个活动顶点”结构。 一旦学生获悉情况，我们就会通过将他们与图表中的继任者联系起来，将他们从考虑中删除。 未来的遍历会自动跳过它们。 

该图是函数图，因此每个节点都只有一个出边。 这使得这个压缩过程特别高效。 节点被处理一次后，它实际上就永远消失了。 

生成的算法在所有时间内最多处理每个学生一次。 这将总工作量减少到接近线性的时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(\sum b_i)$|$O(n)$| 太慢了 |
 | 最佳|$O((n + m)\alpha(n))$|$O(n)$| 已接受 |

 ## 算法演练

 1. 将好友关系图存储为数组`g`， 在哪里`g[x]`下一个叫的学生是`x`。 
2. 维护数组`seen`表明学生之前是否已经听说过任何新闻。 
3.构建DSU式的跳转结构`parent`。 

对于每一个学生`x`,`find(x)`返回可能仍不知情的下一个候选顶点。 
4. 最初，每个顶点都是它自己的代表。 
5.当学生时`x`第一次获悉：

 - 马克`seen[x] = True`。 
- 消除`x`从未来考虑，通过设置：```
parent[x] = find(g[x])
```这意味着未来的遍历直接跳向下一个可能有用的顶点。 
6. 每天：

 - 计算$$a = ((v_i + prev) \bmod n) + 1$$在哪里`prev`是昨天的答案。 

- 开始于`cur = find(a)`。 
7. 同时：

 -`cur`尚未处理，
 - 我们还有剩余的力量，

 处理当前学生。 

每个经过处理的学生都会因为发生一个前进步骤而消耗一单位的力量。 
8.处理完学生后：

 - 增加今天的答案。 
- 将学生从 DSU 结构中删除。 
- 直接跳转到下一个可用的候选人。 
9.输出今天的答案并存储为`prev`。 

### 为什么它有效

 DSU 不变量是：`find(x)`总是返回第一个可以到达的不知情的学生`x`通过反复遵循友谊边缘，跳过所有已经知情的学生。 

每当学生获悉情况后，我们就会永久地将他们引导至下一位候选人。 路径压缩保证未来的搜索变得非常快。 

由于每个学生从不知情到知情的转变只有一次，因此每个节点最多从结构中删除一次。 这限制了所有日子的实际工作总量。 

传播过程本身被准确保留。 我们仍然按照同样的顺序遵循同样的友谊链。 DSU 仅跳过不再影响答案的顶点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

n, m = map(int, input().split())

g = [0] + list(map(int, input().split()))
v = list(map(int, input().split()))
b = list(map(int, input().split()))

parent = list(range(n + 1))
seen = [False] * (n + 1)

def find(x):
    if parent[x] != x:
        parent[x] = find(parent[x])
    return parent[x]

prev = 0

for i in range(m):
    a = ((v[i] + prev) % n) + 1

    ans = 0
    steps = b[i]

    cur = find(a)

    while steps > 0 and not seen[cur]:
        ans += 1
        seen[cur] = True
        steps -= 1

        nxt = find(g[cur])
        parent[cur] = nxt

        cur = nxt

    print(ans)
    prev = ans
```核心思想是，知情的学生将被永久地从未来的遍历中移除。 

这`find`函数执行标准 DSU 路径压缩。 经过足够的操作后，链变得非常短，几乎可以提供恒定时间的访问。 

最微妙的部分是这一行：```
parent[cur] = find(g[cur])
```我们不只是简单地写`parent[cur] = g[cur]`。 该朋友可能已经被删除，因此我们必须直接跳转到下一个活跃代表。 

另一个微妙的细节是循环条件：```
while steps > 0 and not seen[cur]:
```如果`cur`已经被告知了，再继续下去是没有用的。 每个未来通过 DSU 压缩可到达的节点也已从考虑中删除。 

该解决方案从不显式处理循环。 一旦内部的所有顶点都被告知，DSU 压缩就会自然地折叠它们。 

整数溢出在 Python 中无关紧要，但在 C++ 中，此解决方案必须使用 64 位整数来表示涉及的公式`v[i]`。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O((n + m)\alpha(n))$| 每个学生被移除一次，DSU 操作被逆向摊销-Ackermann |
 | 空间|$O(n)$| 友谊图、DSU 父数组和访问数组 |

 反阿克曼因子在实践中实际上是恒定的。 和`n, m <= 10^5`，这很容易符合时间限制。

 - DSU 现在直接在删除的节点之间跳过

 此时每个学生都已被告知，因此该过程停止贡献。 答案是正确的：```
