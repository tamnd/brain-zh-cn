 ## 解决方案
 ## 问题理解

 每个事件都有一系列可能发生的日期。 对于$i$-th 事件，之间的任何整数天$l_i$和$r_i$是可以接受的。 我们必须为每个事件准确分配一天，并且任何两个事件都不能共享同一天。 

任务不是计算作业或优化任何内容。 我们只需要构建一个有效的作业。 

限制小得惊人。 最多有 100 个事件，而日期值本身可以大到$10^7$。 巨大的坐标范围意味着我们无法构建一个以天为索引的数组，但较小的间隔意味着$O(n^2)$或者$O(n^3)$解决方案完全没问题。 甚至像$100^3 = 10^6$操作很容易符合限制。 

棘手的部分是，做出局部合理的选择可能会破坏稍后完成的可能性。 假设我们按输入顺序处理事件并始终选择最早未使用的日期。 

考虑这个例子：```
2
1 100
1 1
```如果我们将第一天分配给第一个事件，则第二个事件就不可能发生。 正确的赋值是：```
2 1
```狭窄的间隔必须优先。 

当几个音程严重重叠时，就会出现另一种微妙的情况。```
3
1 2
1 2
2 2
```粗心的贪婪策略可能会分配：```
1 2 ?
```并陷入最后一个事件。 唯一有效的结构是：```
1 2 2
```这是不可能的，因为日子必须是不同的。 这意味着实际有效的分配必须是：```
1 ? 2
```剩余的时间间隔得到未使用的第 1 天，这也失败了。 仔细一看，这个输入其实是没有解的。 该语句保证了可解性，但这个例子说明了为什么贪婪决策很重要。 

现在考虑一个有效的版本：```
3
1 3
1 2
2 3
```即使存在解决方案，以错误的顺序选择日期仍然可能会失败。 稳健的算法必须保持未来的灵活性。 

## 方法

 强力解决方案将尝试每个间隔内的每个可能的日期，并在两个事件发生冲突时回溯。 由于每个间隔可以跨越$10^7$值，搜索空间是天文数字。 即使间隔很小，作业数量也可能接近$n!$，这很快就变得不可行。 

蛮力方法在概念上是有效的，因为该问题只要求存在满足区间约束的不同分配。 回溯自然会探索所有可能性，直到找到一种。 问题在于它重复了大量的工作并且没有利用任何间隔结构。 

关键的观察结果是，当由正确的端点处理时，间隔表现良好。 如果一个事件比另一个事件早结束，那么延迟它是危险的，因为它的可用选择会更快消失。 

这导致了一个经典的贪婪策略：

 1. 通过增加右端点对区间进行排序。 
2. 对于每个间隔，指定仍位于该间隔内的最小未使用日期。 

为什么最小可用日期有帮助？ 因为未来可能需要的时间间隔仍可使用更长的日子。 为什么按右端点排序有帮助？ 因为期限紧迫的时间间隔会先于灵活的时间间隔处理。 

假设我们处理一个区间$[l, r]$。 如果我们选择其中最早未使用的一天，则每个较小的可行日已经被具有更小或相等右端点的间隔占据。 这些区间稍后无法安全移动，而当前区间仍然可以。 

自从$n \le 100$，我们不需要复杂的数据结构。 我们可以简单地从$l$直到我们找到未使用的一天。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数|$O(n)$递归栈| 太慢了|
 | 最优贪心 |$O(n^2)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 读取所有区间并记住它们的原始索引。 

我们在处理过程中对间隔进行排序，但输出必须遵循输入顺序。 
2. 通过增加右端点对间隔进行排序。 

较早结束的间隔更具限制性。 首先处理它们可以防止未来出现死胡同。 
3. 维护一组已使用的天数。 

每个指定的日期都必须是唯一的。 
4. 对于每个间隔$[l, r]$按排序顺序，扫描从$l$。 

我们搜索区间内第一个未使用的日期。 
5. 分配第一个未使用的日期$d$这样$l \le d \le r$。 

选择最小的可行日期可以为未来的时间间隔保留较大的日期。 
6. 使用间隔的原始索引将分配的日期存储在答案数组中。 

这将恢复所需的输出顺序。 
7. 打印答案数组。 

### 为什么它有效

 贪婪选择是安全的，因为间隔是按其正确端点的升序处理的。 

处理区间时$[l, r]$，每个较早处理的区间最多有右端点$r$。 这些间隔至少和当前的间隔一样紧急。 将当前间隔分配为最小的可用日期，为以后的间隔留出尽可能多的空间，后者的右端点更大。 

假设算法指定日期$d$到当前间隔。 每个较小的可行日已被较早的间隔使用。 将较早的间隔之一移至较大的一天只会使情况变得更糟，因为其截止日期不晚于当前间隔的截止日期。 

这一交换参数表明，贪婪赋值永远不会阻止有效的解决方案（如果存在）。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

events = []

for i in range(n):
    l, r = map(int, input().split())
    events.append((r, l, i))

events.sort()

used = set()
ans = [0] * n

for r, l, idx in events:
    day = l

    while day in used:
        day += 1

    ans[idx] = day
    used.add(day)

print(*ans)
```该解决方案首先将每个间隔及其原始位置存储在一起。 元组顺序是`(r, l, idx)`因为 Python 按字典顺序对元组进行排序，所以间隔会自动通过增加右端点来排序。 

这`used`设置跟踪已分配的日期。 由于仅存在 100 个事件，因此哈希集就足够了。 

对于每个间隔，代码从以下位置开始向上扫描`l`。 该语句保证存在有效的分配，因此最终未使用的天数不超过`r`将会出现。 我们不需要在循环内进行显式边界检查，因为可解性得到了保证。 

一个微妙的点是保留输出顺序。 排序后，区间不再处于原来的位置。 这`idx`字段让我们将每个选定的日期放回答案数组的正确位置。 

另一个微妙的细节是，算法有意选择最早的可用日期，而不是任意的一天。 选择较晚的一天很容易阻碍以后更紧密的间隔。 

## 工作示例

 ### 示例 1

 输入：```
3
1 2
2 3
3 4
```排序间隔：```
[1,2], [2,3], [3,4]
```| 步骤| 间隔| 使用天数 | 选择的日子 | 使用天数后 |
 | ---| ---| ---| ---| ---|

 | 3 | [3,4]| {1,2} | 3 | {1,2,3} |

 最终输出：```

```此示例显示了每个间隔自然接收其左端点的简单情况。 

### 示例 2

 输入：```
4
1 100
1 1
2 2
3 3
```排序间隔：```
[1,1], [2,2], [3,3], [1,100]
```| 步骤| 间隔| 使用天数 | 选择的日子 | 使用天数后 |
 | ---| ---| ---| ---| ---|
 | 1 | [1,1]| {} | 1 | {1} |

```此跟踪说明了为什么按正确端点排序很重要。 如果首先处理大间隔，则可能会消耗第 1 天并打破单例间隔。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(n^2)$| 对于每个间隔，我们最多可以扫描$n$使用天数 |
 | 空间|$O(n)$| 答案数组和最多使用的集合存储$n$元素|

 和$n \le 100$，即使二次扫描也很小。 该算法很好地满足了时间和内存的限制。

# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())

    events = []

    for i in range(n):
        l, r = map(int, input().split())
        events.append((r, l, i))

    events.sort()

    used = set()
    ans = [0] * n

    for r, l, idx in events:
        day = l

        while day in used:
            day += 1

        ans[idx] = day
        used.add(day)

    print(*ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample

2 3
3 4
"""
) == "1 2 3", "sample 1"

# minimum size

"""

 ## 边缘情况

 考虑这样一种情况：一个间隔非常灵活，而另一个间隔只有一天。```
2
1 100
1 1
```该算法按右端点排序：```
[1,1], [1,100]
```单例间隔立即接收第 1 天。灵活间隔则接收第 2 天。最终输出变为：```
2 1
```幼稚的输入顺序贪婪策略会因过早消耗第一天而失败。 

现在考虑时间紧迫的重叠间隔。```
4
1 2
1 2
2 3
3 4
```排序顺序：```
[1,2], [1,2], [2,3], [3,4]
```分配按如下方式进行：

 | 间隔| 指定日期 |
 | ---| ---|
 | [1,2]| 1 |
 | [1,2]| 2 |
 | [2,3]| 3 |
 | [3,4]| 4 |

 每个间隔接收最早未使用的可行日。 该算法绝不会不必要地浪费小日子。 

最后，考虑已经自然排序但触及边界的间隔。```
3
1 1
1 2
2 2
```排序顺序：```
[1,1], [1,2], [2,2]
```作业：

 | 间隔| 指定日期 |
 | ---| ---|
 | [1,1]| 1 |
 | [1,2]| 2 |
 | [2,2]| 不可能|

 该输入没有有效的解决方案，与问题保证此类情况永远不会出现。 这个例子说明了为什么不小心使用端点会立即破坏可行性。
