 ## 解决方案
 ## 问题理解

 我们被要求建造一个长方形盒子，其体积恰好为$V$，其中所有三个边长都必须为正整数。 如果两侧是$a$,$b$， 和$c$，那么约束条件是$a \cdot b \cdot c = V$。 在所有这样的整数三元组中，我们想要产生最小可能表面积的一个，其中表面积是$2(ab + ac + bc)$。 

输入只是一个整数$V$，最多一百万。 输出是一个整数，表示任何具有该体积的整数框可实现的最小表面积。 

约束的关键含义$V \le 10^6$是我们能够枚举因式分解$V$大致在$O(V^{2/3})$或者$O(\sqrt{V})$缩放循环没有问题。 任何尝试所有三倍的事情$V$直接会太慢，因为这将是$10^{18}$运营。 

一个幼稚的错误来自于将其视为连续优化问题和舍入维度。 例如，人们可能会猜测最好的形状接近立方体，因此对于$V = 30$，立方根约为 3，并尝试$3 \times 3 \times 3 = 27$，然后“调整”以适合 30。这完全破坏了整数的可行性。 

另一个微妙的失败案例是任意固定两个维度并导出第三个维度。 如果我们选择$a = 1$总是，然后$b \cdot c = V$，并且我们最小化$2(b + c + bc)$。 这忽略了更好的平衡分解。 为了$V = 36$， 使用$a = 1$给出最好的$b = 6, c = 6$，表面积 84，但最佳值是$3, 3, 4$给予$2(9 + 12 + 12) = 66$。 

真正的困难在于，最佳表面积在很大程度上取决于因子三元组的平衡程度，而不仅仅是成对因子分解。 

## 方法

 暴力方法会枚举所有整数三元组$(a, b, c)$这样$a \cdot b \cdot c = V$。 对于每个候选者，计算表面积并取最小值。 这是正确的，因为它显式检查每个有效配置。 

问题在于复杂性。 的约数个数$V$大致是$O(V^{1/3})$平均每层，但最坏情况枚举仍然变大，因为对于每个$a$，我们考虑因素$V/a$进入$(b, c)$。 这会导致最坏的情况$O(V)$在实践中如果天真地这样做，那就太慢了。 

关键的观察是我们只需要考虑系统生成的因子三元组。 我们可以循环$a$，那么对于每个$a$划分$V$，把问题减少到选择上$b$这样$b$划分$V/a$，并设置$c = (V/a)/b$。 自从$a \le \sqrt[3]{V}$足以进行有意义的枚举（较大的值将迫使已经被对称性覆盖的剩余产品非常小），我们只需要尝试$a$最多$V^{1/3}$，并且类似地$b$最多$\sqrt{V/a}$。 

这将搜索空间减少到大约三次根和平方根层，这对于$V \le 10^6$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（所有三元组）|$O(V^2)$|$O(1)$| 太慢了 |
 | 优化因子枚举 |$O(V^{2/3})$|$O(1)$| 已接受 |

 ## 算法演练

 1.固定一侧$a$并从 1 迭代到$\lfloor V^{1/3} \rfloor$。 我们只考虑除法的值$V$，因为否则没有有效的盒子可以使用它$a$。 
2. 对于每个有效$a$, 计算$rem = V / a$。 这将问题简化为查找两个整数$b$和$c$这样$b \cdot c = rem$。 
3. 迭代$b$从 1 到$\lfloor \sqrt{rem} \rfloor$，同样只保留相除的值$rem$。 这确保我们枚举所有因素对而不重复。 
4. 对于每个有效$b$， 定义$c = rem / b$，并计算表面积$2(ab + ac + bc)$。 这会评估该分解的精确几何形状。 
5. 追踪所有三元组的最小表面积。 在探索了所有因式分解之后，答案就是这个最小值。 

这种方法起作用的重要结构原因是每个整数三元组$(a, b, c)$通过此嵌套因子枚举仅出现一次：选择$a$，然后选择一个除数$b$剩余产品，力$c$独一无二。 

### 为什么它有效

 每个有效框对应于因式分解$V$化为三个整数。 该算法通过首先选择一个因子来枚举所有此类分解$a$，然后将剩余的乘积分解为所有有序对$(b, c)$。 由于基于可分性的迭代恰好覆盖了每个可能的因素一次，因此不会跳过任何有效配置。 因为每个候选者都只被评估一次，并且我们取全局最小值，所以结果必须是最优的。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

V = int(input())

INF = 10**18
ans = INF

limit_a = int(round(V ** (1/3))) + 2

for a in range(1, limit_a + 1):
    if V % a != 0:
        continue
    rem = V // a

    limit_b = int(math.isqrt(rem)) + 1
    for b in range(1, limit_b + 1):
        if rem % b != 0:
            continue
        c = rem // b

        area = 2 * (a*b + a*c + b*c)
        if area < ans:
            ans = area

print(ans)
```外层循环结束$a$将候选人限制为有意义的除数$V$。 立方根界限用于避免一直迭代到$V$，因为超出该点，任何分解都与之前的分解对称，并且不会在表面积最小值方面生成新的三元组。 

内循环枚举剩余商的因子对。 使用`isqrt(rem)`确保我们只检查平方根，并配对$b$和$c = rem // b$避免重复。 

面积计算直接遵循定义，并且全局最小值不断更新。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    V = int(sys.stdin.readline())
    INF = 10**18
    ans = INF

    limit_a = int(round(V ** (1/3))) + 2
    for a in range(1, limit_a + 1):
        if V % a != 0:
            continue
        rem = V // a
        limit_b = int(math.isqrt(rem)) + 1
        for b in range(1, limit_b + 1):
            if rem % b != 0:
                continue
            c = rem // b
            ans = min(ans, 2*(a*b + a*c + b*c))

    return str(ans)

# provided samples
assert run("1\n") == "6", "sample 1"
assert run("6\n") == "22", "sample 2"
assert run("240\n") == "236", "sample 3"

# custom cases
assert run("2\n") == "10", "1x1x2 box"
assert run("12\n") == "32", "best 2x2x3"
assert run("36\n") == "54", "3x3x4 optimal"

 ## 边缘情况

 一个关键的边缘情况是最佳形状高度对称，例如完美的立方体。 为了$V = 64$，算法最终尝试$a = 4$,$b = 4$,$c = 4$, 生产表面积$2(16 + 16 + 16) = 96$。 任何偏态分解，如$1, 8, 8$产生$2(8 + 8 + 64) = 160$，它被最小跟踪正确丢弃。 

另一种边缘情况是当一个维度为 1 时，这种情况经常发生在$V$有很大的质因数。 为了$V = 13$，唯一的分解是$1, 1, 13$，给出表面积$2(1 + 13 + 13) = 54$。 该算法仍然对此进行评估，因为$a = 1$,$b = 1$包含在枚举中，即使在简并因子结构中也能确保正确性。
