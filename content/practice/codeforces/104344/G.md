 ## 解决方案
 ## 问题理解

 弗雷德有一份巧克力蛋清单，每个巧克力蛋都有已知的美分价格和固定金额。 任务是确定如果他选择最佳鸡蛋，他最多可以购买多少个鸡蛋。 每个鸡蛋最多可以购买一次，并且他可以自由选择可用鸡蛋的任何子集。 

输入给出了可用鸡蛋的数量、金额和价格列表。 输出是一个整数，表示总成本不超过预算的最大项目数。 

关键的限制是鸡蛋的数量可以多达 100000 个。任何试图考虑所有子集甚至所有组合的解决方案都是立即不可行的。 在最坏的情况下，二次方法需要大约 10^10 次运算，这远远超出了时间限制。 

当价格差异很大时，就会出现唯一重要的边缘情况。 例如，如果除了一件便宜的商品之外所有商品都很昂贵，那么不优先考虑小价值的幼稚策略可能会过早浪费预算。 当列表未排序并且贪婪方法假设顺序很重要而没有显式排序时，会出现另一种失败模式。 

一个简单的例子，其中顺序很重要：

 输入：```
3
5
5 4 1
```正确答案是`1`，因为购买成本为 1 的物品是最优的。 如果粗心地选择第一个可负担的前缀而不进行排序，则可能会根据输入顺序出现不可预测的错误行为。 

另一个边缘情况：

 输入：```
4
10
8 7 6 5
```正确的输出是`1`。 任何在没有排序的情况下尝试组合的策略都将无法有效地最大化计数。 

## 方法

 强力解释是尝试鸡蛋的所有子集，计算它们的总成本，并跟踪其总和不超过预算的最大子集。 这是正确的，因为它显式地评估每个可能的选择，但它作为 2^N 个子集呈指数增长，甚至检查每个子集的成本为 O(N)，导致 O(N·2^N) 时间。 当N达到100000时，这是不可能的。 

更好的观察来自于重新设定目标。 我们并不是要追求价值最大化或成本最小化； 我们正在最大化项目数量，这表明每个项目对目标的贡献相同。 由于无论价格如何，每件商品的答案都会+1，因此最佳策略是首先购买最便宜的商品。 

一旦我们按照升序对价格进行排序，我们就可以贪婪地一件一件地拿走物品，直到预算用完。 这是有效的，因为任何包含更昂贵的物品而排除更便宜的物品的解决方案都可以通过交换它们来改进，从而减少或保留总成本而不减少数量。 

这将问题简化为排序加上单个线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N·2^N) | O(N·2^N) | O(N) | 太慢了 |
 | 排序 + 贪心 | O(N log N) | O(N log N) | O(1) 或 O(N) | 已接受 |

 ## 算法演练

 1. 读取 N（鸡蛋数量）和 C（可用预算）。 
2. 阅读价格表。 
3. 按非降序对列表进行排序，以便较便宜的商品排在前面。 

排序是必要的，因为局部决策取决于成本的全局排序。 
4. 初始化一个计数器，用于记录已购买的物品和连续的花费金额。 
5. 迭代排序后的价格。 
6. 对于每个价格，检查将其添加到当前支出金额是否仍在预算范围内。 

如果是，请将其包含在内并更新支出金额和计数器。 

如果没有，请立即停止，因为所有剩余的物品至少同样昂贵。 
7. 输出计数器。 

为什么它有效：

 在这个过程中的任何一点，我们都选择了给定大小的最便宜的可能子集。 如果存在一个包含更多物品的更好解决方案，它必然会用更便宜的未使用物品替换某些选定的昂贵物品，这与我们总是按升序处理物品的事实相矛盾。 贪心选择保持了这样的不变性：在 k 步之后，我们在大小为 k 的所有子集中拥有最小可能的成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = int(input())
    p = list(map(int, input().split()))
    
    p.sort()
    
    used = 0
    total = 0
    
    for price in p:
        if total + price <= c:
            total += price
            used += 1
        else:
            break
    
    print(used)

if __name__ == "__main__":
    solve()
```解决方案首先对价格进行排序，以便我们始终首先考虑更便宜的鸡蛋。 变量`total`跟踪到目前为止所花的钱，以及`used`计算有多少个鸡蛋被选中。 循环保持了我们总是采用下一个最便宜的可行项目的不变性。 提前停止条件是安全的，因为一旦价格超过剩余预算，所有后续价格至少都一样大。 

一个微妙的细节是使用严格的预算检查`total + price <= c`。 这确保了我们永远不会超出限制，即使在剩余预算与价格完全匹配的边界情况下也是如此。

 ## 边缘情况

 当所有物品都比预算贵时，就会出现一种边缘情况。 排序后，第一项已经违反了约束，因此循环立即终止并且输出保持为零。 例如：

 输入：```
3
2
5 6 7
```排序后`[5, 6, 7]`，第一次比较失败并且没有发生更新，产生输出`0`。 

另一种情况是，多个项目的价格相同，等于不同阶段的剩余预算。 条件`total + price <= c`确保平等被正确接受。 例如：

 输入：```
4
10
2 2 2 4
```执行：

 首先取 3 个 2，总共达到 6 个，然后取 4 个，正好达到 10 个。该算法正确地允许每一步相等，确保实现最大计数。
