 ## 解决方案
 ## 问题理解

 我们被问到是否可以精确分配$K$糖果之间$N$受到两种约束的儿童。 每个孩子必须至少接受$L$糖果，任何孩子收到的糖果不得超过$R$糖果。 我们必须决定是否存在任何整数分配可以在使用所有糖果时同时满足所有孩子的需求。 

这从根本上来说是有限分配的可行性问题。 每个孩子贡献一个变量$x_i$这样$L \le x_i \le R$，以及所有的总和$x_i$必须等于$K$。 问题归结为是否$K$位于由这些有界变量形成的总和的总可实现范围内。 

约束足够小，任何$O(N)$或者$O(1)$计算是微不足道的。 价值观$N \le 10^3$,$K \le 10^6$， 和$R \le 10^5$意味着我们不应该模拟分布或搜索分配。 相反，我们应该专注于导出总和的严格下限和上限。 

当最小可能总数已经超过时，就会出现微妙的边缘情况$K$，或者当最大可能总数仍然小于$K$。 另一个边缘情况是当$L = R$，这迫使每个孩子收到完全相同数量的糖果，从而将问题变成严格的可除性检查。 例如，如果$N = 3$,$L = R = 3$，那么唯一可能的总数是$9$。 任何$K \neq 9$必须立即失败。 

另一个极端情况是$L = 0$，这允许一些孩子什么也得不到，但上限仍然限制总数。 在这种情况下，可行性完全取决于是否$K \le N \cdot R$。 

## 方法

 暴力解释会尝试逐个分配糖果。 对于每个孩子，我们可以尝试之间的每个值$L$和$R$，递归地分配剩余的糖果，直到所有$N$孩子们被分配了值。 这产生了大约的分支因子$R - L + 1$每个孩子，导致$(R-L+1)^N$可能的配置。 即使界限很小，这也是不可行的，因为$N$可以达到$10^3$，使得枚举量变得巨大。 

关键的观察是我们不关心个体分布，只关心总和是否存在。 每个孩子在固定的时间间隔内独立贡献，因此所有可能的总和的集合形成从最小可实现总和到最大可实现总和的连续范围。 

当每个孩子都收到时，金额就会达到最小$L$, 给予$N \cdot L$。 当每个孩子都收到时，金额就会达到最大$R$, 给予$N \cdot R$。 由于我们可以以整数步独立调整每个子项，因此这两个极端之间的每个整数值都是可以实现的。 因此，问题简化为检查是否$K$位于区间内$[N \cdot L, N \cdot R]$。

 ## 算法演练

 1. 计算最小糖果总数为$N \cdot L$。 这表示每个孩子收到的最低允许金额的情况，并且任何有效的分配都不能低于该值。 
2. 计算最大糖果总数为$N \cdot R$。 这代表每个孩子收到允许的最大金额的情况，并且任何有效的分配都不能超过该值。 
3. 检查是否$K$就在这个区间之内。 如果$N \cdot L \le K \le N \cdot R$，则存在有效分布； 否则，它不会。 
4. 输出`'S'`如果可行，否则输出`'N'`。 

步骤 3 背后的原因是，由于每个孩子的贡献可以在相同的范围内独立增加或减少，因此总和不会被分割成缺口。 相反，它形成了可实现的整数的连续范围。 

### 为什么它有效

 关键的不变量是，在处理任何子集之后，可实现的总和形成一个连续的区间。 最初，在孩子数为零的情况下，唯一可实现的总和是$0$。 添加一个子项会通过添加一个值来扩展每一个可实现的总和$[L, R]$，它会移动并联合间隔但​​不会产生间隙。 重复这个$N$times 保持连续性，因此最终的总和集恰好是 之间的所有整数$N \cdot L$和$N \cdot R$。 因此，检查该区间内的成员资格既是必要的也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, K, L, R = map(int, input().split())
    
    min_sum = N * L
    max_sum = N * R
    
    if min_sum <= K <= max_sum:
        print('S')
    else:
        print('N')

if __name__ == "__main__":
    solve()
```实现直接遵循派生边界。 唯一需要的计算是两次乘法和一次比较。 使用 Python 的任意精度整数可以避免任何溢出问题，即使中间值达到$10^8$或更高。 

决策逻辑放在最后，以清楚地反映数学条件。 不需要额外的数据结构或循环。

 ## 边缘情况

 一个重要的边缘情况是当$L = R$，这迫使所有孩子收到相同数量的糖果。 对于输入：```
3 9 3 3
```该算法计算$min\_sum = 9$和$max\_sum = 9$。 自从$K = 9$，条件完全成立，输出为`'S'`。 任何与 9 的偏差都会立即失败，因为区间会塌陷到一个点。 

另一个边缘情况是当$L = 0$，允许灵活分配：```
5 7 0 3
```这里$min\_sum = 0$,$max\_sum = 15$。 由于 7 位于该区间内，因此算法正确输出`'S'`。 关键是，即使个别孩子可以收到零，但上限仍然只能通过总最大值来限制可行性。 

第三种边缘情况是当$K$非常大，但仍在整数运算的范围内：```
1000 1000000 0 1000
```最大可能的总和恰好是$1{,}000{,}000$，所以答案是`'S'`。 该算法无需溢出或特殊大小写即可处理此问题，因为 Python 整数会自然缩放。
