 ## 解决方案
 ## 问题理解

 我们得到了一个小的数字网格。 从这个网格中，我们可以重复删除整行或整列。 每次删除都会永久删除该行或列中的所有值，并且表的其余部分保持不变。 

任何删除序列后的最终结果始终是通过选择某些行子集和某些列子集，然后精确保留它们的交集而形成的矩形子矩阵。 删除的顺序对于最终结构并不重要，重要的是哪些行和列保留下来。 

任务是确定是否存在某种幸存行和列的选择，使得所有剩余单元格的总和等于目标值，如果是，则输出实现该目标的删除序列。 

网格大小最多为 15 x 15，因此最多有 225 个单元格。 这立即表明对行和列的指数推理是可以接受的。 任何独立尝试所有子集的解决方案都已经接近可行，但我们必须小心：所有子矩阵的简单枚举大约为 2^(30)，如果直接完成，这个值太大了。 

关键的结构约束是我们从不重新排序元素或部分删除行或列。 这意味着最终形状完全由两个独立的子集决定：所选的行和所选的列。 

当所有数字都很大但目标总和很小时，就会出现微妙的边缘情况。 例如，如果每个单元格都是正数，并且最小行和已经大于 s，则不存在解。 假设“删除更多总是有帮助”的天真的方法仍然必须尊重删除行也会删除相交列的所有贡献，因此除非我们明确地根据完整的行/列子集进行推理，否则部分直觉可能会失败。 

另一个极端情况是当 s 等于矩阵的总和时。 在这种情况下，不需要删除，答案就是简单的零操作。 

最后，所有值都为零的情况是退化的：任何子矩阵的总和为零，因此行和列的任何非空选择只要它非空，都是有效的。 

## 方法

 中心观察是，通过选择一组行 R 和一组列 C，并精确保留所有单元格 (i, j)（其中 i 位于 R 且 j 位于 C 中）来完全确定最终表格。因此，总和为：

 sum(R, C) = R 中所有 i、C 中 j 的 A[i][j] 之和。 

暴力方法将枚举所有行子集和所有列子集，计算每对的总和，并检查它是否等于 s。 有 2^h 行子集和 2^w 列子集，给出大约 2^(h+w) 个状态，最多为 2^30。 每个总和计算成本为 O(hw)，使其速度太慢。 

关键的简化是颠倒观点：我们可以固定一侧并求解另一侧，而不是同时选择行和列。 对于行 R 的固定子集，每列独立地贡献这些行上的列总和。 一旦 R 固定，我们就选择一个列的子集，其权重（这些列的总和）必须总计为 s。 这是最多 15 个元素的标准子集和问题。 

这将问题转化为两级搜索：枚举行子集，计算导出的列权重，然后求解列上的子集总和。 因为 w ≤ 15，所以每行子集的子集总和在 O(w 2^w) 内是可行的，从而导致总体 O(h 2^h w 2^w)，这完全在限制范围内。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解 (R, C) | O(2^(h+w) · hw) | O(2^(h+w) · hw) | O(1) | O(1) | 太慢了|
 | 行子集 + 列子集和 | O(h 2^h + h w 2^w) | O(h 2^h + h w 2^w) | O(w 2^w) | O(w 2^w) | 已接受 |

 ## 算法演练

1. 预先计算任意行子集的列总和。 对于每个行子集 R，我们构建一个数组 colSum[j]，它存储仅限于 R 中行的列 j 的总和。这将 2D 选择问题简化为列上的 1D 加权选择问题。 
2. 对于选定的行子集 R，通过 colSum 隐式计算所有选定单元格的总基数和。 
3. 求解是否存在列 C 的子集，使得 C 中 j 上的 colSum[j] 之和等于 s。 这是最多 15 个项目的标准子集总和，因此我们可以使用列的位掩码枚举。 
4. 如果存在这样的列子集，我们重构解决方案：删除不在 R 中的行，删除不在 C 中的列。 删除的顺序并不重要，但我们必须尊重原始表编号中的索引。 
5. 以任何有效顺序输出删除，通常首先删除不在 R 中的所有行或首先删除不在 C 中的所有列。 

为什么它有效：每个有效的最终配置都唯一对应于一对（R，C）。 相反，每个这样的对都通过删除互补的行和列来对应于可达配置。 该算法探索所有可能的 R 以及每个可能的导出列子集 C，确保整个搜索空间的完整性，而不会丢失任何结构可能性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    h, w = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(h)]
    s = int(input())

    # Precompute all row masks
    H = h
    W = w

    # Precompute row bit contributions per column for each row subset
    # col_sum[mask][j] = sum over i in mask of a[i][j]
    col_sum = [[0] * w for _ in range(1 << h)]

    for mask in range(1 << h):
        if mask == 0:
            continue
        lb = mask & -mask
        i = (lb.bit_length() - 1)
        prev = mask ^ lb
        if prev == 0:
            for j in range(w):
                col_sum[mask][j] = a[i][j]
        else:
            for j in range(w):
                col_sum[mask][j] = col_sum[prev][j] + a[i][j]

    full_rows = (1 << h) - 1

    for rmask in range(1 << h):
        cols = col_sum[rmask]

        for cmask in range(1 << w):
            total = 0
            for j in range(w):
                if cmask >> j & 1:
                    total += cols[j]

            if total == s:
                # reconstruct operations
                print("YES")
                ops = []

                # delete rows not in rmask
                for i in range(h):
                    if not (rmask >> i & 1):
                        ops.append((1, i + 1))

                # delete columns not in cmask
                for j in range(w):
                    if not (cmask >> j & 1):
                        ops.append((2, j + 1))

                print(len(ops))
                for t, idx in ops:
                    print(t, idx)
                return

    print("NO")

if __name__ == "__main__":
    solve()
```实现直接遵循行掩码枚举策略。 这`col_sum[mask][j]`表是使用标准子集 DP 技巧构建的：每个掩码都分解为其最低有效位和更小的子掩码，确保每个状态只计算一次。 

修复行子集后，我们将每列视为单个聚合权重。 然后我们枚举所有列子集并计算它们的总和。 这是故意对列进行暴力破解，因为 w ≤ 15 使得 2^w 操作可以接受。 

重建很简单：我们输出所有未选择的行和所有未选择的列的删除。 该问题允许任何顺序，因此我们只是按顺序列出它们。 

一个常见的实现陷阱是从头开始为每个行掩码重新计算列总和，这会增加一个额外的 h 因子，虽然没有必要，但仍然可能通过。 DP 优化使其保持干净和一致。

| 行掩码| 列总和 | 列子集| 总计 |

 对于行掩码 110（保留前两行），列总和变为 [3,5,4]。 选择第 1 列和第 2 列得出 3 + 5 = 8。 

然后我们删除第 3 行和第 3 列，生成正确的配置。

```任何行子集生成的列总和都是 2 的倍数。因此，任何列子集总和也是偶数。 目标5是不可能的。 

该算法仍然检查所有掩码，但从未找到匹配项，因此返回“否”。

 ## 边缘情况

 单细胞网格是最干净的边界。 如果 A[1][1] 等于 s，则算法找到 rmask = 1 且 cmask = 1 并立即返回。 如果不是，则没有子集匹配，结果为“否”。 

全零矩阵强调许多掩码产生相同的和。 该算法仍然枚举所有行和列子集，但每个配置的计算结果为零，因此只有 s=0 成功。 

s 等于总和的情况会触发 rmask = full 和 cmask = full。 该算法在枚举早期检测到它并且不输出删除，这是有效的，因为允许空操作序列。
