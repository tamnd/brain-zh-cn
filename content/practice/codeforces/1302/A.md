 ## 解决方案
 ## 问题理解

 我们正在使用矩形数字网格。 每个单元格的行为就像二维游戏中的玩家：它与其列垂直比较，与其行水平比较。 

如果一个单元格同时是其列中的严格最大值和其行中的严格最小值，则该单元称为纳什均衡。 换句话说，向下看它的列，没有其他值可以匹配或超过它，并且向下看它的行，没有其他值可以匹配或低于它。 

任务就是找到这样一个细胞。 如果多个单元格满足条件，我们选择按行顺序最早出现的单元格，如果仍然存在平局，则选择按列顺序最早出现的单元格。 如果不存在这样的单元格，我们输出零。 

约束允许最多 1000 x 1000 个单元格，即最多 100 万个值。 这立即排除了任何重复扫描整个行和列以查找每个候选单元格的解决方案。 幼稚的每个单元格验证需要检查其整个行和列，从而导致大约$O(nm(n + m))$操作，在最坏的情况下速度太慢。 

当值重复时，就会出现一个微妙的问题。 粗心的实现可能会使用非严格比较或仅部分检查来处理“列中的最大值”或“行中的最小值”，这会破坏正确性。 

例如，考虑一列`[1, 5, 5, 2]`。 如果我们只检查一个值是否等于最大值而不强制唯一性，则两个 5 都可能被视为有效的列最大值，但定义需要对所有其他行进行严格的支配，这会因重复而失败。 

当最佳行最小值和列最大值在结构上不一致时，就会出现另一种边缘情况。 一行可能具有唯一的最小值，但该位置不是列最大值，因此每行的本地推理是不够的。 

## 方法

 蛮力的想法很简单。 对于每个单元格，我们验证两个条件：它必须严格大于其列中的所有其他值，并且严格小于其行中的所有其他值。 每次验证都会花费行或列长度的线性时间。 因为我们可能会检查到$10^6$细胞，每个成本高达$O(1000)$，总工作量变为$10^9$，对于两秒来说太大了。 

关键的观察是条件可以独立预先计算。 对于每一行，我们只需要它的最小值和它出现的列索引。 对于每一列，我们只需要它的最大值和它出现的行索引。 有效平衡必须恰好位于行最小值和列最大值的交点处。 

这极大地减少了搜索空间。 我们不测试每个单元格，而是仅检查从行最小值或列最大值派生的候选者，并验证每个候选者在恒定时间内的一致性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(nm(n+m))$|$O(1)$| 太慢了 |
 | 最佳 |$O(nm)$|$O(n + m)$| 已接受 |

 ## 算法演练

 我们通过预先计算行最小值和列最大值来构建解决方案，然后将这些约束相交。 

1. 对于每一行，扫描所有列并存储最小值及其列索引。 如果最小值出现多次，我们仍然保留第一个位置，因为平局更喜欢较小的列索引。 
2. 对于每一列，扫描所有行并存储最大值及其行索引。 同样，通过优先选择最小的行索引来解决关系。 
3. 迭代所有行。 对于每一行，获取其存储的最小位置$(i, j)$。 
4. 在每个候选位置，检查值是否在$(i, j)$等于列的最大值$j$。 这确保了列的主导地位。 
5. 如果两个条件都匹配，则将此单元格记录为有效候选答案。 
6. 由于行按升序处理，并且我们选择每行中的第一个有效列索引，因此会自动选择按字典顺序排列的最小有效单元格。 

### 为什么它有效

 有效的纳什均衡必须同时满足其行和列的局部极值条件。 行条件强制单元格成为行最小值之一，列条件强制它成为列最大值之一。 任何有效的解决方案都必须出现在两个预先计算的结构中。 通过仅枚举行最小值并针对列最大值进行验证，我们保证永远不会错过解决方案，同时避免检查不相关的单元格。 迭代的顺序确保了字典最少性，无需额外排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    row_min_val = [10**18] * n
    row_min_idx = [-1] * n

    col_max_val = [-10**18] * m
    col_max_idx = [-1] * m

    for i in range(n):
        for j in range(m):
            v = a[i][j]
            if v < row_min_val[i]:
                row_min_val[i] = v
                row_min_idx[i] = j
            if v > col_max_val[j]:
                col_max_val[j] = v
                col_max_idx[j] = i

    for i in range(n):
        j = row_min_idx[i]
        if j == -1:
            continue
        if a[i][j] == col_max_val[j]:
            print(i + 1, j + 1)
            return

    print(0, 0)

if __name__ == "__main__":
    solve()
```该实现首先在矩阵上一次传递中构建两个辅助数组。 行数组捕获每行中的最小元素及其列位置。 列数组捕获每列中最大的元素及其行位置。 

第二阶段仅检查行最小值，因为任何有效的均衡都必须是行最小值。 对于每一行最小值，我们验证它是否也是其列的列最大值。 如果是这样，它就满足这两个约束。 

一个常见的陷阱是试图在不进行预先计算的情况下独立地执行每个单元的两个条件，这会导致二次扫描。 另一个错误是不尊重严格的比较语义，特别是如果替换`<`或者`>`和`<=`或者`>=`，这打破了均衡定义。

    a = [list(map(int, input().split())) for _ in range(n)]

                col_max_val[j] = v

 ## 边缘情况

 一个重要的边缘情况是一行具有多个相同的最小值。 在这种情况下，选择其中任何一个都可能导致不同的列检查。 该算法通过始终记录第一次出现来避免歧义，从而保留字典顺序的优先级。 

另一种情况是列最大值出现在多行中。 其中只有一个可以同时满足行最小约束。 相交检查确保仅接受两个方向都极值的像元。 

第三种情况是网格包含常量值时。 从非严格意义上来说，每个单元格都是行最小值和列最大值，但严格的不等式会消除所有候选者。 该算法不会正确返回任何解，因为在所需方向上没有任何值严格大于或小于其邻居。
