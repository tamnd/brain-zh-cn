 ## 解决方案

 ## 问题理解

 我们给定一个二进制字符串，将其视为一行仅包含`0`和`1`。 从这一长行中，我们滑动一个固定大小的窗口`k`跨越所有可能的起始位置。 每个位置产生一个长度的子串`k`，每个子字符串本身就是一个二进制字符串。 

任务不是列出这些子串或直接以幼稚的方式将它们进行成对比较，而是简单地计算有多少个不同的长度模式`k`出现在字符串中的任何位置。 

所以输出是大小不同的唯一“窗口”的数量`k`当我们从左到右扫描时。 

约束允许字符串长度最大为 200,000。 对所有子串进行简单的比较将涉及多达 200,000 个窗口，并且每次比较的成本为 O(k)，导致大约为 O(nk)，在最坏的情况下可以达到 4×10^10 次操作。 这已经远远超出了时间限制。 

关键的观察是每个子字符串都很短（二进制字母表），因此我们需要一种方法在预处理后在 O(1) 中比较子字符串，或者以紧凑的可哈希形式表示它们。 

当所有字符都相同时，会出现微妙的边缘情况。 例如，如果`s = 00000`和`k = 3`，每个子串都是相同的，所以答案是`1`。 错误地使用非滚动重新计算的简单哈希方法可能会由于重新计算错误或标准化不一致而意外地将相同的子字符串视为不同的子字符串。 另一个边缘情况是当`k = 1`，其中答案只是不同字符的数量，总是`1`或者`2`。 

## 方法

 暴力解决方案将提取每个长度的子串`k`，将其存储为字符串，并将其插入到集合中。 这在逻辑上是正确的，因为集合处理唯一性。 然而，复制每个子串的成本为 O(k)，并且对 O(n) 个位置执行此操作会使总成本为 O(nk)，这对于上限来说太慢了。 

为了改善这一点，我们注意到子字符串严重重叠。 从一个窗口移动到下一个窗口只会改变两个角色：一个离开窗口，一个进入窗口。 这种结构暗示了滚动表示。 

由于字母表是二进制的，我们可以将每个子字符串解释为以 2 为基数的数字。然后每个窗口对应一个整数，我们可以使用位操作在 O(1) 中更新这个整数：左移、添加新位并屏蔽超出长度的旧位`k`。 这给了我们一个没有冲突的滚动哈希。 

这减少了维护滑动二进制值并将每个值插入集合的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nk) | O(nk) | 每个子串 O(k) | 太慢了|
 | 滚动二进制哈希 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1.转换第一个窗口的大小`k`通过将其解释为二进制数来转换为整数。 这给出了子字符串的紧凑表示。 
2. 将此整数插入到哈希集中。 该集合存储迄今为止看到的所有不同的窗口值。 
3. 对于每个位置`i`从`k`到`n - 1`，更新当前值：

 我们左移 1 位（相当于乘以 2），添加新的位`s[i]`，并通过掩蔽消除掉出窗口的位的贡献`(1 << k) - 1`。 
4. 将每个更新的值插入到集合中。 每个值唯一标识一个长度的子串`k`。 
5. 答案是处理完所有窗口后集合的大小。 

步骤 3 的关键思想是我们从不重构子字符串。 我们重用之前的计算并在本地调整它，这保持了运行时的线性。 

### 为什么它有效

 每个子串的长度`k`当以基数 2 解释时，对应于唯一的二进制数。滚动更新保留整数表示和当前窗口内容之间的精确等价性。 由于每个窗口都被访问一次并确定性地映射到一个数字，因此子字符串的相等性恰好对应于集合中存储的整数的相等性。 不会引入冲突，因为表示是精确的而不是散列的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    if k == 0:
        print(0)
        return

    mask = (1 << k) - 1

    val = 0
    for i in range(k):
        val = (val << 1) | (ord(s[i]) - 48)

    seen = {val}

    for i in range(k, n):
        val = ((val << 1) & mask) | (ord(s[i]) - 48)
        seen.add(val)

    print(len(seen))

if __name__ == "__main__":
    solve()
```代码维护一个滚动整数`val`总是代表最后的`k`字符串的位。 掩码确保旧的位一旦移出窗口就被删除。 套装`seen`跟踪遇到的所有不同值。 

一个常见的错误是忘记掩码操作，这会导致位超出长度`k`累积和破坏窗口之间的比较。 另一个微妙的问题是正确初始化第一个窗口； 如果不这样做，所有比较都会发生变化并产生错误的计数。

 ## 边缘情况

 当字符串由所有相同的字符组成时，每个窗口都映射到相同的整数，因为除了在相同位内移位之外，滚动值永远不会改变。 用于输入`s = 000000`和`k = 3`，每个计算值仍然保留`0`，所以设定的大小为`1`。 

什么时候`k = 1`，每个窗口只是一个位。 滚动机制退化为直接将每个字符的整数值插入到集合中。 为了`s = 0101`，值在之间交替`0`和`1`，恰好产生两个不同的元素。 

什么时候`k = n`，只有一个窗口，因此初始编码已经代表完整的字符串，并且设置的大小始终为`1`。
