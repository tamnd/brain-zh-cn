 ## 解决方案

 ## 问题理解

 我们得到一个无向图，其中两个顶点之间的每个连接都有一个非负权重。 任务是确定从顶点 1 行进到顶点 n 所需的最小可能总权重，或者报告如果没有边序列连接它们，则这是不可能的。 

这是在最多具有 200,000 个顶点和 200,000 个边的加权图上进行的经典最短路径查询。 每个边缘成本可以高达 10^9，因此任何解决方案都必须使用 64 位整数仔细管理累积和。 

约束大小立即排除了任何试图彻底重新计算路径的方法。 单纯的广度优先搜索是无效的，因为边权重不均匀。 Floyd-Warshall 风格的全对计算是不可能的，因为它需要 O(n^3) 时间。 即使没有结构的重复弛豫也会退化到 O(nm)，当 n 和 m 都很大时，这太慢了。 

一种微妙的边缘情况来自断开的图。 例如，如果输入是：```
4 2
1 2 3
3 4 5
```那么从1到4就没有路径了，正确的输出是-1。 任何错误地初始化距离或假设可达性的实现都会错误地返回一个大的默认值，而不是识别这种断开连接。 

另一个重要的情况是同一对顶点之间的多条边。 由于图并不简单，两个节点之间可能存在几种不同的成本。 正确的解决方案必须始终考虑最便宜的有效过渡，而不是盲目覆盖或假设唯一性。 

## 方法

 一种直接但不正确的方法是尝试探索从 1 到 n 的所有可能路径，累积每条路线的成本并跟踪最小值。 顶点数量很快就会呈指数增长，因为图中的每个分支都会使所考虑的部分路径的数量加倍。 即使重新修剪也只能稍微改善情况，但最坏的情况仍然会爆炸，因为可以通过许多不同的成本上下文到达相同的顶点。 

一种更结构化的尝试是运行广度优先的类似搜索的遍历，同时每当找到更短的路径时放宽距离。 仅当所有边具有相同的权重时，此方法才有效，但此处的情况并非如此。 对于任意权重，BFS 可能会过早确定节点并错过后来发现的更便宜的路径。 

关键的观察结果是所有边权重都是非负的，因此一旦我们知道到顶点的当前最佳暂定距离，我们就可以安全地以距离递增的顺序扩展顶点。 这正是 Dijkstra 算法所需的条件。 我们不会盲目探索，而是总是处理已知距离最小的下一个顶点，保证当它被处理时，它的最短距离就是最终的。 

使用最小堆优先级队列可以有效地维护此顺序。 每次我们提高到节点的距离时，我们都会将其推入堆中。 每次提取都会为我们提供下一个最有希望扩展的顶点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力路径枚举| 指数| O(n) | 太慢了|
 | Dijkstra 与最小堆 | O((n + m) log n) | O((n + m) log n) | O(n + m) | 已接受 |

 ## 算法演练

 1. 构建图的邻接列表表示。 每个顶点将所有传出边存储为（邻居，成本）对。 这种结构允许在松弛期间对邻居进行快速迭代。 
2. 初始化一个距离数组，其中每个顶点都设置为无穷大，除了顶点 1 设置为 0。这编码了我们以零成本从节点 1 开始的事实。 
3. 创建一个最小堆优先级队列并插入 (0, 1) 对。 堆用于始终扩展当前最接近的已知顶点。 
4. 当堆不为空时，提取已知距离 d 最小的顶点 u。 该顶点代表最有希望的边界点。 
5. 如果提取的距离 d 大于存储的 u 距离，则跳过它。 这可以防止处理在发现更好的路径之前推送的过时的堆条目。 
6. 对于 u 的每个边权重为 w 的邻居 v，检查通过 u 到达 v 是否改善了其当前的最佳已知距离。 如果 d + w 小于 dist[v]，则更新 dist[v] 并将 (dist[v], v) 压入堆中。 此步骤从已确认的最短路径向外传播改进。 
7. 堆耗尽后，检查dist[n]。 如果仍为无穷大，则输出-1； 否则输出 dist[n]。 

### 为什么它有效

 该算法依赖于以下属性：一旦从优先级队列中删除所有候选节点中距离最小的节点，该距离就是最终的。 到该节点的任何替代路径都必须经过具有相同或更大暂定距离的另一个节点，这不能在不与堆强制执行的顺序相矛盾的情况下产生更小的结果。 这保证了每个节点都按照真实最短距离的升序排列，从而确保所有松弛的正确性。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

n, m = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(m):
    a, b, c = map(int, input().split())
    g[a].append((b, c))
    g[b].append((a, c))

dist = [INF] * (n + 1)
dist[1] = 0

pq = [(0, 1)]

while pq:
    d, u = heapq.heappop(pq)

    if d != dist[u]:
        continue

    for v, w in g[u]:
        nd = d + w
        if nd < dist[v]:
            dist[v] = nd
            heapq.heappush(pq, (nd, v))

print(-1 if dist[n] == INF else dist[n])
```邻接表构造确保每条边恰好存储两次，每个方向一次，因为图是无向的。 距离数组使用较大的哨兵值来表示未到达的顶点，Python 的任意精度整数可以安全地处理较大的路径总和，而不会出现溢出问题。 

堆总是存储候选状态，而检查`d != dist[u]`有效地丢弃过时的条目。 如果没有这种检查，算法仍然是正确的，但由于冗余扩展而速度较慢。

 ## 边缘情况

 断开连接的图，例如`1-2`和`3-4`测试是否正确检测到不可达节点。 到节点 n 的距离保持无穷大，算法返回 -1，而不尝试无效路径。 

相同节点之间的多个边确保松弛逻辑不会假设唯一性。 在有边缘的测试用例中`1-2 (10)`和`1-2 (2)`，堆处理两者，但只有较小的权重更新距离，并且算法正确地传播值 2。 

直接边比间接路径差的图表凸显了按距离排序的重要性。 到节点 4 的直接边是 100，但链 1→2→3→4 产生 3。堆确保节点以增加成本的方式扩展，从而允许首先发现较短的多步路径并正确覆盖最初的直接猜测。
