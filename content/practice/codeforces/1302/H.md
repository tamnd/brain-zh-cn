 ## 解决方案
 ## 问题理解

 我们给定一个长度的序列`n`。 虽然该语句谈论的是字符串，但字符是用整数表示的，而且字母表非常大。 字母表的大小意味着我们不能依赖依赖于少量不同符号的技巧。 

每个查询指定两个起始位置和一个长度。 我们必须确定该长度的两个连续段是否相同。 

更具体地说，对于一个查询`(len, pos1, pos2)`，我们比较：

 -`a[pos1 ... pos1 + len - 1]`-`a[pos2 ... pos2 + len - 1]`并打印`"Yes"`如果每个对应元素都匹配，否则`"No"`。 

约束是问题的关键部分。 两个都`n`和`q`可以达到20万。 直接比较两个子字符串需要`O(len)`时间。 在最坏的情况下，`len`也是200,000，所以单个查询可能需要200,000次比较。 如果有 200,000 个查询，则大约变为`4 × 10^10`元素比较，远远超出了2秒的限制。 

该任务实际上是对静态序列进行大量子串相等性检查。 该结构强烈建议构建一个预处理数据结构，可以在恒定或对数时间内回答每个查询。 

一些边缘情况值得关注。 

考虑相同的起始位置：```
n = 5
a = [1,2,3,4,5]

query: len=5, pos1=1, pos2=1
```答案是显而易见的`"Yes"`。 任何正确的子字符串比较方法都必须处理这个问题，没有特殊情况。 

考虑到达数组末尾的比较：```
n = 5
a = [1,2,3,4,5]

query: len=2, pos1=4, pos2=4
```比较的段是`[4,5]`。 这里经常出现前缀计算中相差一的错误。 

另一个重要的情况是两个子字符串共享一个很长的公共前缀但结尾不同：```
a = [7,7,7,7,8]
query: len=5, pos1=1, pos2=?
```仅检查部分前缀的粗心优化可能会错误地得出相等性的结论。 整个长度必须通过防碰撞表示进行验证。 

最后，字母表包含最多 987,898,788 的值。 任何假设字符适合小字母表的方法（例如固定大小的频率数组或按字符值索引的转换表）都是不合适的。 

## 方法

 暴力解决方案很简单。 对于每个查询，逐个元素比较两个请求的子字符串。 如果所有位置都匹配，则输出`"Yes"`; 否则输出`"No"`。 

暴力方法是正确的，因为子字符串相等性是通过每个位置的相等性精确定义的。 问题是它的运行时间。 查询可能需要`O(len)`工作，以及`len`或许`O(n)`。 和`q = 200000`和`n = 200000`，最坏的情况变成`O(nq)`，大约四百亿次比较。 

数组永远不会改变，并且每个查询都会提出同一类型的问题：两个范围是否相等？ 我们可以预处理序列并为每个前缀分配一个紧凑的指纹，而不是重复检查底层元素。 那么就可以在常数时间内提取任意子串的指纹。 

多项式滚动哈希是一个自然的选择。 让$$H[i]$$表示第一个的哈希值`i`元素。 使用固定基数的幂，可以从两个前缀哈希恢复任何子字符串的哈希。 

如果两个子字符串相等，则它们的哈希值也相等。 使用双重散列，不同子字符串产生同一散列对的概率可以忽略不计。 预处理后，每个查询都会减少为比较两个哈希对，这需要恒定的时间。 

暴力解决方案重复检查相同的元素。 散列将每个子字符串压缩为恒定大小的表示形式，从而允许立即回答每个查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 最坏情况 O(nq) | O(1) | O(1) | 太慢了|
 | 最优（双滚动哈希）| O(n + q) | O(n) | 已接受 |

 ## 算法演练

 1. 读取序列。 
2、选择两个大模数和一个固定底座。 
3. 预先计算以两个模为模的基数的幂。 

这些能力使我们能够在恒定时间内标准化子字符串哈希。 
4. 为两个模构建前缀哈希数组。 

对于每个位置，通过附加当前值来扩展先前的前缀哈希。 
5. 定义函数`get_hash(l, r)`返回子数组的哈希对`l`到`r`包容性。 

使用前缀哈希：$$H(l,r)=H[r]-H[l-1]\cdot P^{r-l+1}$$对每个模数进行模计算。 
6. 对于每个查询，将从 1 开始的位置转换为相应的区间端点。 
7. 计算第一个子字符串的哈希对。 
8. 计算第二个子串的哈希对。 
9. 如果两个哈希对相同，则打印`"Yes"`，否则打印`"No"`。 

### 为什么它有效

 前缀哈希结构保证每个子字符串都由其元素的多项式表达式表示。 删除子字符串之前的前缀的贡献会产生仅取决于子字符串本身的值。 

两个相等的子字符串生成完全相同的多项式，因此生成完全相同的哈希对。 每个查询都会比较两个请求范围的哈希表示。 由于两个哈希值都是使用相同的公式提取的，因此相等的子字符串总是比较相等。 双散列使意外冲突的可能性微乎其微，这是用于子字符串相等查询的标准竞争编程保证。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    MOD1 = 1_000_000_007
    MOD2 = 1_000_000_009
    BASE = 911382323

    pow1 = [1] * (n + 1)
    pow2 = [1] * (n + 1)

    for i in range(1, n + 1):
        pow1[i] = (pow1[i - 1] * BASE) % MOD1
        pow2[i] = (pow2[i - 1] * BASE) % MOD2

    pref1 = [0] * (n + 1)
    pref2 = [0] * (n + 1)

    for i in range(n):
        pref1[i + 1] = (pref1[i] * BASE + a[i] + 1) % MOD1
        pref2[i + 1] = (pref2[i] * BASE + a[i] + 1) % MOD2

    def get_hash(l, r):
        h1 = (
            pref1[r]
            - pref1[l - 1] * pow1[r - l + 1]
        ) % MOD1

        h2 = (
            pref2[r]
            - pref2[l - 1] * pow2[r - l + 1]
        ) % MOD2

        return h1, h2

    ans = []

    for _ in range(q):
        length, p1, p2 = map(int, input().split())

        h_first = get_hash(p1, p1 + length - 1)
        h_second = get_hash(p2, p2 + length - 1)

        ans.append("Yes" if h_first == h_second else "No")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```预处理阶段构建基础哈希和前缀哈希的幂。 两个数组都是从零开始索引，而子串查询自然是使用从1开始的位置来表达，所以哈希提取公式就直接写成从1开始的形式。 

添加`1`在将每个元素插入散列之前对每个元素进行处理，可以防止零值在前导位置变得不可见。 如果不进行这种调整，某些多项式表示的鲁棒性就会降低。 

这`get_hash`功能是关键部分。 它消除了位置之前所有内容的贡献`l`并仅留下与请求的间隔相对应的多项式。 间隔的长度决定了必须移除哪个功率倍增器。 

每个查询计算两个哈希对并比较它们。 不需要遍历底层子字符串。

 输入：```

```涉及的子串有：

 | 查询 | 第一个子串 | 第二个子串 | 结果 |

 | 查询 | 范围 1 | 范围 2 | 哈希值相等吗？ | 输出|

 | 2 | [1,3]| [3,5]| 没有 | 没有 |

 这个例子演示了主要思想：相等性测试变成哈希比较而不是元素比较。 

### 自定义示例

```所有子字符串完全由值组成`5`。 

| 查询 | 范围 1 | 范围 2 | 哈希值相等吗？ | 输出|
 | ---| ---| ---| ---| ---|
 | 1 | [1,1]| [6,6]| 是的 | 是的 |

        pow2[i] = (pow2[i - 1] * BASE) % MOD2

    pref2 = [0] * (n + 1)

 ## 边缘情况

 考虑最小可能的实例：```
1 1
7
1 1 1
```唯一的子串是`[7]`。 范围的哈希值`[1,1]`计算两次并与自身进行比较。 两个哈希值都匹配，所以答案是`"Yes"`。 

考虑一个触及数组末尾的查询：```
5 1
1 2 3 4 5
2 4 4
```比较的范围是`[4,5]`和`[4,5]`。 哈希函数恰好提取两个元素，因为幂项中使用的长度为`r - l + 1 = 2`。 不包含任何额外元素，也不遗漏任何元素。 

考虑两个具有长公共前缀的范围：```
5 1
7 7 7 7 8
4 1 2
```比较的子串是：```
[7,7,7,7]
[7,7,7,8]
```前三个位置匹配，但最后一个不同。 它们的多项式哈希值不同，因为最终系数贡献不同的值。 算法输出`"No"`。 

考虑相同的起始位置：```
5 1
1 2 3 4 5
5 1 1
```两个查询的区间是完全相同的范围。 提取的哈希对相同，算法返回`"Yes"`立即通过正常的比较逻辑。 无需特殊处理。
