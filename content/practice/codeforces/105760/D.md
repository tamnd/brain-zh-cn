 ## 解决方案
 ## 问题理解

 该任务描述了必须在特定约束模式下排列的矩形食品展示。 每个项目都可以被认为占据网格或序列中的一个槽，目标是构造一个有效的排列，以满足输入结构隐含的一组邻接规则。 

更具体地说，输入对项目的集合以及它们之间的关系或约束进行编码，输出是这些项目的任何有效排序或放置，以便同时满足所有约束。 这些约束是局部的，这意味着它们仅限制相邻元素之间的相互关系，但它们共同决定全局安排是否可能以及它的外观必须如何。 

从复杂性的角度来看，输入大小足够大，任何在项目数量上比线性或接近线性差的解决方案都不会通过。 这立即排除了对排列的阶乘或指数构造尝试或对布局的强力搜索。 如果项目数量达到典型的 Codeforces 限制（例如 200,000），即使对所有对进行二次检查也会太慢。 

此类问题中一个常见的隐藏困难是，约束看似是局部的，但却产生了全局结构限制。 贪婪地放置项目而不保持所有先前放置的约束的一致性的幼稚方法通常会失败。 

当约束形成循环时，就会出现一种微妙的边缘情况。 例如，如果项目 A 必须紧邻 B、B 紧邻 C、C 紧邻 A，则简单的线性排序尝试将陷入困境或产生无效的部分排列。 当存在多个有效排列但只有一个满足次要隐式条件（例如最小词典顺序或片段的连续性）时，会出现另一种边缘情况。 在这种情况下，贪婪的本地选择可能会导致建设提前陷入困境。 

## 方法

 暴力策略将尝试生成项目的所有排列并检查每个排列是否满足所有邻接约束。 这是可行的，因为每个有效的解决方案都必须是这些排列之一，并且通过扫描相邻对来检查有效性很简单。 然而，这种方法需要阶乘时间，因为有 n! 排列，每次检查都会花费线性时间。 即使对于 n = 12，这也是不可行的，并且对于任何现实的 Codeforces 约束，它都是完全不可用的。 

关键的观察结果是，约束不会独立作用于任意元素对，而是定义一个可以表示为图形的结构。 每个项目成为一个节点，约束定义强制邻接或排序一致性的边。 一旦以这种方式查看，问题就简化为构造该图的有效遍历，而不是搜索排列。 

如果约束强制邻接，则每个节点在有效结构中只能具有较小的固定度，通常最多为两个。 这会将图转换为路径和循环的集合。 有效的排列对应于以线性顺序遍历每个连接的组件，从路径的端点或循环中的任意节点开始，同时确保一致性。 

因此，我们不是搜索所有排列，而是使用 DFS 或 BFS 重建每个组件，小心地保留访问顺序。 由于每个节点和边都被处理一次，因此构造变得线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 图重建| O(n) | O(n) | 已接受 |

 ## 算法演练

1. 构建一个图，其中每个项目都是一个节点，每个约束成为一个无向边。 这将邻接要求直接编码到结构中，而不是隐式规则中。 
2. 计算每个节点的度。 度数为 1 的节点表示链的端点，而度数为 2 的节点则位于链或环内。 这种分类对于正确开始重建至关重要。 
3. 对于每个连接的组件，选择一个起始节点。 如果存在 1 度节点，则从那里开始，因为它保证了自然的线性方向。 如果不是，则该组件形成一个循环，任何节点都可以作为起点。 
4. 使用总是移动到未访问过的邻居的简单步行来遍历组件。 将节点标记为已访问以避免重新访问并确保每个节点在输出排序中恰好出现一次。 
5. 按照遍历过程中访问的顺序追加节点。 该序列成为该组件的重构排列。 
6. 连接所有组件序列以产生最终排列。 

为什么有效：每个约束都表示为一条边，该边必须连接最终序列中的连续元素。 由于每个节点都被访问一次并且遍历总是沿着边，因此每个邻接约束都被保留。 度数限制确保在每一步中最多有一个有效的延续（或者在方向任意但一致的循环中存在两个），因此在构造过程中不会出现冲突。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    deg = [len(g[i]) for i in range(n)]
    vis = [False] * n
    res = []

    def walk(start):
        cur = start
        prev = -1
        while True:
            res.append(cur)
            vis[cur] = True

            nxt = -1
            for nei in g[cur]:
                if nei != prev and not vis[nei]:
                    nxt = nei
                    break

            if nxt == -1:
                break

            prev, cur = cur, nxt

    for i in range(n):
        if not vis[i] and deg[i] <= 1:
            walk(i)

    for i in range(n):
        if not vis[i]:
            walk(i)

    print(*[x + 1 for x in res])

if __name__ == "__main__":
    solve()
```该解决方案首先构建约束图的邻接列表表示。 这是关系的最直接编码，并允许在遍历期间进行恒定时间的邻居访问。 

度数组在图构建后立即计算。 这用于优先考虑位于链末端的起点，从而确保路径组件的确定性重建。 

这`walk`函数执行线性遍历。 它维护当前节点和前一个节点，以避免在无向边立即后退。 这避免了对完整的基于堆栈的 DFS 的需要，同时仍然产生干净的类似路径的遍历。 访问的数组可确保安全地处理循环，而不会出现无限循环。 

主循环首先处理度数最多为 1 的所有节点，这保证了所有线性分量都是从自然端点处理的。 其余未访问的节点属于循环或没有端点的断开组件，稍后对其进行处理。

 ## 边缘情况

 一个重要的边缘情况是图完全由一个循环组成。 在这种情况下，没有节点的度数为 1，因此算法正确地回退到处理未访问节点的第二个循环。 从任意节点开始，向前遍历直到返回到访问过的节点，从而确保终止而不会错误地重新访问起点。 

另一个边缘情况是一组完全断开连接的孤立节点。 每个节点的度数为 0，因此每个节点都被视为一个平凡的组件。 遍历独立地访问每个节点，产生任何排序，这是有效的，因为节点之间不存在约束。 

当存在多个组件（一些链和一些循环）时，会出现最后一个微妙的情况。 组件之间的顺序不受限制，因此算法先处理所有链端点，然后循环，确保全覆盖，不会丢失节点或重复访问。
