 ## 解决方案
 ## 问题理解

 我们得到一系列按固定顺序放置在书架上的书籍。 每本书都有两个属性：它的宽度，它额外影响了盒子必须覆盖的水平空间的大小，以及它的高度，它决定了如果包含该书，盒子必须有多高。 

我们必须将序列精确地划分为 k 个连续的段。 每个段对应一个盒子，盒子内的书籍必须保持原来的顺序，并且在书架上是连续的。 对于选定的段，盒子的成本是通过将该段中所有书籍的宽度总和乘以这些书籍中的最大高度来计算的。 

目标是选择 k 个切割位置，使所有段的总成本最小化。 

输入由 n 个有序书籍和 k 个盒子组成。 输出是单个可能的最小总成本。 

该结构立即表明线性序列上的划分问题。 每个分割仅取决于连续的间隔，并且间隔的成本取决于类似前缀的聚合：总和和最大值。 这种组合通常表示间隔内的动态规划解决方案。 

约束允许最多 n = 1000，这排除了为每个状态从头开始重新计算区间属性的任何三次 DP。 如果可以有效地维护区间统计，则二次或接近二次的 DP 是可以接受的。 

一些角落情况对于正确性很重要。 

如果 k = n，则每本书都被隔离在自己的盒子中。 成本变成 wi × hi 之和。 任何意外合并一对相邻对的解决方案都会根据高度顺序低估或高估。 

如果 k = 1，则所有书籍都在一个盒子中，因此答案为（所有宽度之和）×（最大高度）。 这对于 DP 初始化和转换都是有用的健全性检查。 

另一个微妙的情况是高度不单调。 例如，在局部高度最大值处的贪婪切割可能会失败：该段早期的一本高书会增加成本，即使它最好放置在单独的盒子中，但隔离它可能会增加稍后的宽度倍增。 这会破坏任何仅基于本地决策的贪婪结构。 

## 方法

 暴力解决方案会尝试各种方法在书之间的 n-1 个间隙中放置 k-1 个切口。 对于每个分区，我们通过重新计算每个段的宽度和最大高度之和来评估每个段。 这导致每个段和 O(k) 个段的复杂度为 O(n)，因此一种配置的成本为 O(n)。 分区数量为 C(n − 1, k − 1)，呈指数增长。 即使对于中等的 n，这也是不可行的，因为配置的数量已经超过了任何合理的计算限制。 

关键的观察结果是，一旦我们固定了线段的右端点 j，如果我们在扫描时维护宽度的前缀和并跟踪最大高度，则可以在 O(1) 内计算将前一个线段边界 i 扩展到 j 的成本。 这将问题转换为选择前缀的 k 个分区，其中转换仅取决于分割点 i。 

这个结构是一个经典的区间 DP：状态表示恰好使用 t 个盒子覆盖前 i 本书的最小成本。 过渡枚举最后的剪切位置。 

预先计算宽度的前缀和并使用转换内高度的运行最大值可确保在恒定时间内计算每个间隔成本，从而留下 O(n^2 k) DP。 由于 k 可以达到 n，我们通过观察来进一步减少它，我们只需要两层上的 DP，并且转换仍然是 O(n^2)。 当 n ≤ 1000 时，这是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分区| O(C(n,k) · n) | O(C(n,k) · n) | O(n) | 太慢了 |
 | 具有前缀优化的间隔 DP | O(n²k) | O(n·k) | 已接受 |

 ## 算法演练

我们将 dp[t][i] 定义为将前 i 本书放入 t 个盒子的最小成本。 

1. 预先计算宽度前缀和，以便在常数时间内获得 sum(i, j)。 这允许快速评估任何框宽度。 
2. 将框数 t 从 1 迭代到 k。 对于每个 t，我们计算所有前缀 i 的 dp[t][i]。 
3. 对于dp[1][i]，没有选择：从1到i的所有书都在一个盒子里，所以我们计算最大高度，同时从左到右累加宽度。 
4. 对于 t ≥ 2，通过考虑每个可能的最后切割位置 j < i 来计算 dp[t][i]。 最后一个盒子覆盖了书j+1到i，所以它的成本是（宽度之和j+1..i）×（最大高度j+1..i）。 
5. 为了有效地计算步骤 4，我们固定 i 并向后扫描 j，同时保持宽度和最大高度的运行总和。 这避免了重复重新计算段属性。 
6. 转换变为 dp[t][i] = min over j of dp[t−1][j] + cost(j+1, i)。 我们在 O(n) 中对所有 j 进行评估，每层给出 O(n²)。 
7. 最终答案是dp[k][n]。 

### 为什么它有效

 前 i 本书到 t 个盒子的每个有效分区都有一个唯一的最后切割位置 j。 DP 将所有此类可能性仅枚举一次。 由于分段成本仅取决于分段本身，而不取决于先前的选择，因此在 j 处进行分割可以将问题清楚地分成最佳前缀解决方案和最终的独立分段。 递归通过取所有有效最后段的最小值来保持最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    w = [0] * (n + 1)
    h = [0] * (n + 1)

    for i in range(1, n + 1):
        wi, hi = map(int, input().split())
        w[i] = wi
        h[i] = hi

    INF = 10**30

    dp_prev = [INF] * (n + 1)
    dp_cur = [INF] * (n + 1)

    dp_prev[0] = 0

    for t in range(1, k + 1):
        dp_cur = [INF] * (n + 1)

        for i in range(1, n + 1):
            sum_w = 0
            max_h = 0
            best = INF

            for j in range(i, 0, -1):
                sum_w += w[j]
                if h[j] > max_h:
                    max_h = h[j]

                cost = sum_w * max_h
                if dp_prev[j - 1] + cost < best:
                    best = dp_prev[j - 1] + cost

            dp_cur[i] = best

        dp_prev = dp_cur

    print(dp_prev[n])

if __name__ == "__main__":
    solve()
```该实现仅保留两个 DP 层以减少内存。 内循环从 i 向后走到 1，保持当前后缀的总宽度和最大高度，这与最后一个候选框完全对应。 dp 转换使用 dp_prev[j−1]，因为 j 标记最终段的开始。 

一个常见的差一错误是混合 j 代表段的开始还是结束。 这里 j 被视为最后一个框的第一个元素，因此先前的 DP 状态在 j−1 处结束。
