 ## 解决方案
 ## 问题理解

 我们正在模拟不断增长的计算机通信网络。 最初，每台计算机都是孤立的，因此每台计算机都形成自己的组。 随着时间的推移，计算机对之间会添加连接，这些连接会将组合并为更大的连接组件。 

在任何时候，网络都由多个连接的组件组成。 对于每个组件，我们关心它的大小。 我们要求维护的数量是这些组件的函数平均值：我们取每个组件，对其大小进行平方，将这些平方大小相加，然后除以图中当前组件的数量。 在每次添加边或查询之后，我们必须输出当前状态的平均值。 

关键的困难在于，随着边缘的添加，组件的数量及其大小都会动态变化，并且查询可以出现在序列中的任何点。 

输入大小高达约 300,000 个操作，因此任何每次操作从头开始重新计算连接组件的解决方案都会太慢。 完全重新计算至少花费节点数量的线性时间，导致不可行的二次最坏情况。 

基于联合查找的结构立即成为自然的候选者，因为它有效地支持动态合并。 

有一些微妙的边缘情况往往会破坏简单的解决方案。 一是忘记合并同一组件中已有的两个节点根本不应该改变结构。 例如，如果我们尝试多次连接 1 和 2：

 输入：```
3 3
1 2
2 3
1 2
?
```最后一条边不会改变任何内容，因此分量数和平方和必须保持不变。 盲目合并的幼稚 DSU 实现可能会错误地将组件数量减少两倍。 

另一种边缘情况是所有节点保持隔离。 然后每个分量的大小为 1，因此答案始终为 1，因为平方和为 n，分量的数量为 n。 

最后，在报告比率时，浮点精度很重要。 整数除法会默默地破坏正确性。 

## 方法

 强力模拟显式地维护完整的图。 每次操作后，我们从每个未访问的节点运行 DFS 或 BFS 来计算所有连接的组件，跟踪它们的大小，然后计算所需的总和。 这是正确的，因为它在每一步都直接遵循组件的定义。 

然而，每次重新计算的成本为 O(n + m)，并且最多可以有 3×10^5 次操作。 在最坏的情况下，这会导致大约 10^10 次操作，这远远超出了任何合理的限制。 

关键的观察是我们维护的结构只合并组件，从不拆分它们。 这使得该问题适合不相交集并集结构。 DSU 允许我们逐步跟踪组件大小。 当两个组件合并时，我们只需要更新一些聚合值，而不是重新计算所有内容。 

剩下的挑战是在合并下有效地表达组件大小的平方和。 如果大小为 a 和 b 的两个分量合并，则平方和的变化为：

 (a + b)² − a² − b² = 2ab

 因此我们可以在每个联合的恒定时间内维护全局总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（每次重新计算组件）| O(n·m) | O(n + m) | 太慢了 |
 | 具有维护聚合的 DSU | O(m α(n)) | O(m α(n)) | O(n) | 已接受 |

 ## 算法演练

 我们维护一个不相交集并集结构和两个全局值：连接组件的数量和组件大小的平方和。 

1. 初始化DSU，每个节点作为自己的父节点，大小为1。此时，每个节点都是一个单独的组件，因此组件数量为n，平方和也为n。 
2. 对于 u 和 v 之间的每个边添加，找到它们的 DSU 代表。 这告诉我们它们属于哪些组件。 
3. 如果两个节点已经在同一个组件中，我们什么都不做。 结构和所有总量保持不变。 
4. 如果它们属于不同的组件，我们将较小的组件合并到较大的组件中。 这使 DSU 保持高效并确保近乎恒定的时间运行。 
5. 设两个分量的大小为a 和b。 我们通过添加 2ab 来更新全局平方和，因为 (a+b)² 取代了 a² + b²。 我们还将组件数量减 1。 
6. 处理完一个操作后，如果是查询，我们输出 sum_of_squares / Components 的当前值。 

正确性依赖于以下事实：所有所需信息仅取决于组件大小，并且 DSU 在联合运算下准确维护这些大小。 每次合并都会根据平方的代数恒等式更新聚合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return 0
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        added = 2 * self.size[a] * self.size[b]
        self.size[a] += self.size[b]
        return added

def solve():
    n, m = map(int, input().split())
    dsu = DSU(n)

    comp = n
    sumsq = n

    out = []

    for _ in range(m):
        parts = input().split()

        if parts[0] == '?':
            if comp == 0:
                out.append("0.000000")
            else:
                out.append(str(sumsq / comp))
        else:
            u = int(parts[0]) - 1
            v = int(parts[1]) - 1

            added = dsu.union(u, v)
            if added:
                comp -= 1
                sumsq += added

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```DSU 类处理连接，同时压缩路径以保持操作快速。 union 函数仅在合并实际发生时返回一个值，这可以防止出现冗余边时出现错误更新。 

主循环保持两个不变量：comp始终等于DSU根的数量，sumsq始终等于分量大小的平方和。 查询只是读取这两个值。 

一个常见的实现错误是仅使用 a² + b² 更新 sumsq，而不是添加正确的 delta 2ab。 这会导致重复计算或丢失合并组件的贡献。

 ## 边缘情况

 一个关键的边缘情况是重复并集。 假设我们多次连接同一对。 DSU 确保第二次及以后的尝试返回而不修改结构，因此组件计数和总和都不会改变。 例如，当 n = 3 时：

 合并 1 和 2 后，我们得到大小为 2 和 1 的分量。如果我们尝试再次合并 1 和 2，find() 将为两者返回相同的根，因此跳过并集并且总和保持正确。 

另一种边缘情况是图从未接收到任何边。 每个查询的答案都是 1，因为平方和为 n 并且有 n 个分量。 该算法精确地初始化为此状态并且永远不会修改它，除非发生并集。 

最后一个微妙的情况是大 n 没有查询，只有联合。 DSU 的行为仍然正确，因为所有更新都是本地的并且与查询时间无关，并且聚合在每次合并后仍然有效。
