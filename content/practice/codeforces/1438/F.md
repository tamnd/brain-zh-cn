 ## 解决方案
 ## 问题理解

 给定一个高度完美的二叉树$h$，其中包含$n = 2^h - 1$节点。 每个节点都有一个唯一的标签，从 1 到$n$，但标签完全未知。 我们的任务是确定根的标签。 我们可以通过特殊类型的查询与树进行交互：对于任何三个不同的标签$u$,$v$,$w$，查询返回最低共同祖先 (LCA)$u$和$v$如果树的根在$w$。 

主要挑战是 LCA 与假设的根相关$w$，不是真正的根。 这使得直接从单个查询推导出真正的根变得很棘手。 此外，查询的数量大致限制为$n + 420$，仅略多于节点总数。 因此，任何查询每个三元组的算法都是不可行的。 树的大小为$h = 18$是$n = 262143$，所以我们买不起$O(n^2)$或者$O(n^3)$蛮力方法。 

一种简单的方法可能会尝试查询每个节点三元组或尝试重建完整的树，但这两种方法都需要太多的查询。 边缘情况包括所有节点都是根的直接子节点的小树，或者使用非常接近根的节点查询树的情况，如果不仔细考虑根，可能会返回意外的 LCA 结果。 

我们的见解是，当使用随机对和随机根进行查询时，通过观察哪些节点最频繁地显示为 LCA，可以从概率上检测到真正的根。 由于根在层次结构中占主导地位，因此它往往比非根节点更频繁地显示为 LCA。 

## 方法

 暴力方法将尝试通过查询节点的所有组合来完全重建树。 每个查询都会在假设的根下返回一个 LCA，并且通过组合足够多的这些结果，理论上可以推断出每个节点的父子关系。 然而，所需的查询数量约为$O(n^3)$，对于$h = 18$并且无法满足查询限制$n + 420$。 

关键的见解是我们不需要完整的树。 无论假设的根是什么，根都是唯一可以作为节点对的 LCA 出现的节点。 因此，我们可以对随机三元组进行采样，并计算哪个节点最常作为 LCA 出现。 作为真正根的节点很有可能比任何其他节点更频繁地作为 LCA 返回。 通过将采样三元组的数量限制为几倍$n$，我们可以在保持查询限制的情况下可靠地识别根。 

这种方法将问题从重建整个树简化为概率计数问题。 根作为 LCA 频率中的主导节点出现，这是一种更便宜的计算和查询策略。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^3) | O(n^3) | O(n^2) | O(n^2) | 太慢了 |
 | 随机抽样| 预期 O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.读取高度$h$并计算$n = 2^h - 1$。 
2.初始化一个size的计数器数组$n+1$跟踪每个标签作为 LCA 出现的频率。 
3. 重复几次$n$迭代次数：

 1. 随机选择三个不同的标签$u$,$v$,$w$介于 1 和$n$。 
2.通过“? u v w”查询分级机，读取返回的标签$x$。 
3. 增加计数器$x$。 
4. 采样后，找到计数最高的标签。 这个标签就是根。 
5. 输出“!r”，标签标识为根。 

工作原理：在完美二叉树中，真正的根具有独特的属性：它是每个节点的祖先。 无论查询中选择何种假设根，实际根比任何其他节点更频繁地作为 LCA 显示，因为没有其他节点可以同时控制树的大部分。 随机抽样确保根以高概率出现为最频繁的 LCA。 

## Python 解决方案```python
import sys, random
input = sys.stdin.readline

def main():
    h = int(input())
    n = 2**h - 1
    
    counts = [0] * (n + 1)
    
    # We choose a constant factor of n for safety; this keeps us under n+420 queries
    for _ in range(min(n + 400, 4 * n)):
        u, v, w = random.sample(range(1, n+1), 3)
        print(f"? {u} {v} {w}")
        sys.stdout.flush()
        x = int(input())
        counts[x] += 1
    
    root = counts.index(max(counts))
    print(f"! {root}")
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```主要的微妙之处在于正确处理交互式查询：我们必须在每次打印后刷新输出。 随机采样就足够了，因为真根在 LCA 计数中占主导地位。 我们还使用`min(n + 400, 4 * n)`以确保我们不会超出查询限制。

 ## 边缘情况

 对于高度为 3、标签为 [1,2,3,4,5,6,7] 的树，如果我们只查询叶子，简单的方法可能会错误地选择叶子作为根，因为叶子可以作为某些假设根下的 LCA 返回。 我们的算法对包括内部节点在内的多个随机三元组进行采样。 结果，真正的根作为 LCA 重复出现，占主导地位。 即使叶子偶尔出现为 LCA，它的频率也永远不会超过根。 随机抽样保证我们以高概率识别出正确的根。
