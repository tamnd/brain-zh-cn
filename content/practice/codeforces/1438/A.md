 ## 解决方案
 ## 问题理解

 该问题要求我们构造具有非常严格的整除性的数组。 对于一个被称为完美的数组，每个子数组，无论长度或位置如何，都必须有一个可被其长度整除的和。 唯一的附加约束是数组的每个元素必须介于 1 到 100 之间（包含 1 和 100）。 我们给出了多个测试用例，每个测试用例都指定了所需的数组长度`n`，并且我们必须输出满足条件的任意长度的数组。 

看看约束条件，`n`最多为 100，测试用例的数量也最多为 100。这意味着每个测试用例的运行时间约为 O(n) 或 O(n²) 的任何算法都将高效运行，因为操作总数最多约为 10⁴。 不需要先进的数据结构或优化技术。 

问题的关键非显而易见部分是完美数组的定义。 天真的尝试可能会尝试测试所有可能的数字序列或构建每个子数组的总和，但这是不必要的。 我们需要注意一个强有力的模式：如果一个数组的所有元素都相等，那么每个子数组也由相等的数字组成，使得总和可被长度整除。 例如，`[5,5,5]`有效，因为每个子数组的总和是`5*k`对于某些人来说`k`，可除以`k`。 

边缘情况包括最小的`n = 1`，它适用于 1 到 100 之间的任何数字。另一个边缘情况是`n = 100`，最大允许长度，我们必须确保所有数字都在界限内并且相同。 

## 方法

 暴力方法将尝试生成数组并检查每个子数组。 对于给定长度的数组`n`， 有`n*(n+1)/2`子数组，并且在最坏的情况下检查每个总和需要 O(n)。 这导致每个测试用例的操作次数为 O(n³)。 和`n`最多 100 次，每个测试用例可能会达到 100 万次操作，这对于一次测试来说是可行的，但浪费且不必要，而且如果天真地通过重复求和来实现，很容易超出时间限制。 

最佳方法来自这样的观察：如果数组的所有元素都相等，则每个子数组都有总和`element_value * length_of_subarray`。 由于这个总和显然可以被子数组长度整除，因此该数组自动是完美的。 因为元素值可以是 1 到 100 之间的任意数字，所以我们可以选择`1`或该范围内的任何常量，并且数组将满足条件。 

这种方法将问题简化为生成长度数组`n`用单个数字填充。 每个测试用例的时间复杂度为 O(n)，并且基本满足边界和所有条件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(n²) | 太慢而且没必要 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，读取整数`n`表示所需数组的长度。 
3.生成一个长度的数组`n`每个元素在哪里`1`。 1 到 100 之间的任何数字都可以，但是`1`很简单。 
4. 将数组打印为空格分隔的行。 

这样做的原因是任何长度的子数组`k`将有总和`1*k`，可除以`k`。 这个不变量对于所有的情况都成立`k`从 1 到`n`。 无需考虑其他值或组合，这保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        # perfect array: all elements equal, choose 1
        print(' '.join(['1'] * n))

if __name__ == "__main__":
    solve()
```代码的每一部分都直接对应于算法。 我们读取测试用例的数量，然后对于每个`n`生成一个数组。 使用`' '.join(['1'] * n)`是一种将输出构造为空格分隔字符串的 Python 方式，避免手动循环或格式错误。

 ## 边缘情况

 对于`n = 1`，算法输出`[1]`。 任何子数组的长度均为 1，且总和 1 可被 1 整除。对于`n = 100`，输出是`[1]*100`。 任意长度的子数组`k`有总和`k`，可除以`k`。 选择 1 可保证所有值都在 1..100 范围内。 不存在差一或和溢出问题，因为所有算术都是微不足道的。
