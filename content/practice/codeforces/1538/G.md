 ## 问题理解

 我们有两堆糖果。 一堆包含`x`红色糖果和其他包含`y`蓝色糖果。 

每套礼品必须准确使用`a + b`糖果。 有两种可能的组合：

 -`a`红色和`b`蓝色的
-`b`红色和`a`蓝色

 这两种类型是对称的。 对于每组，我们可以自由选择任一方向。 一颗糖果最多可以使用一次。 

任务是计算可以组成的最大礼品套装数量。 

约束是主要线索。 所有值都可以大到`10^9`，并且最多有`10^4`测试用例。 任何试图一一模拟礼品套装的算法都是不可能的。 即使单个测试用例也可能有接近的答案`10^9`。 

解决方案围绕`O(log 10^9)`每个测试用例都很好，因为`10^4 × 30 ≈ 3 × 10^5`运营。 答案中的任何线性内容都被排除。 

一些边缘情况很容易被忽略。 

考虑：```
x = 1, y = 1, a = 2, b = 2
```每组总共需要四颗糖果，但只有两颗糖果。 答案是：```
0
```仅基于平衡颜色的天真检查可能会错误地认为一组是可能的。 

现在考虑：```
x = 1000000000
y = 1
a = 1
b = 1000000000
```一组可以通过采取`1`红色和`1000000000`蓝色，反之亦然。 由于蓝色糖果稀缺，只能制作一套。 正确答案是：```
1
```任何只考虑糖果总数的公式都会错误地预测出更大的答案。 

另一种微妙的情况发生在`a = b`。```
x = 10
y = 12
a = b = 3
```每组恰好消耗三颗红色糖果和三颗蓝色糖果。 不再有方向自由了。 答案变成：```
min(10 // 3, 12 // 3) = 3
```通用解决方案仍然必须正确处理这种退化情况。 

## 方法

 强力策略是猜测有多少组使用第一个方向，有多少组使用第二个方向。 

假设我们想要创建`k`总套数。 让`t`其中有`(a red, b blue)`和`k - t`是`(b red, a blue)`。 

总红色消耗变为：```
t·a + (k - t)·b
```总蓝色消耗量变为：```
t·b + (k - t)·a
```我们可以尝试每一个可能的值`t`并检查可行性。 这是正确的，因为每种排列都对应于某些选择`t`。 

问题是`k`本身可以接近`10^9`。 甚至检查所有值`t`对于单个候选人来说，答案的成本太高了。 

关键的观察结果是答案是单调的。 

如果可以创建`k`礼品套装，那么也可以制作任意数量较少的礼品套装。 我们可以简单地丢弃一些集合。 

单调性立即建议对答案进行二分搜索。 

现在问题变成：

 > 给定一个候选值`k`，我们可以确定是否`k`礼品套装可以吗？ 

让`t`再次表示第一方向的组数。 

资源限制是：```
t·a + (k - t)·b ≤ x
t·b + (k - t)·a ≤ y
```重新排列后：```
t(a - b) ≤ x - kb
t(a - b) ≥ ka - y
```这些不等式描述了有效值的区间`t`。 

而不是寻找`t`，我们只需要知道这个区间是否包含整数。 

这将可行性检查变成了恒定时间算术计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每次可行性检查 O(k) | O(1) | O(1) | 太慢了|
 | 最佳 | O(log(min(x,y))) | O(log(min(x,y))) | O(1) | O(1) | 已接受 |
