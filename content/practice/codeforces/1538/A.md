 ## 解决方案
 ## 问题理解

 我们有一排石头，每块石头都有不同的强度值。 一步中，我们只能移走两块界石中的一颗，要么是最左边的，要么是最右边的。 最终，我们想要移除阵列中最弱的石头和最强的石头。 

任务是确定在删除两个极值之前所需的此类边界删除的最小数量。 

从约束中观察到的关键是每个测试用例都很小，最多有 100 个石头。 这立即排除了对许多状态的高级数据结构或模拟的任何需要。 即使每个测试用例的 O(n) 或 O(n^2) 解决方案也足够快。 

天真的解释可能建议模拟左右删除的所有可能序列，直到两个目标元素都被删除，但这会导致可能性呈指数级增长。 即使 n = 100，这也是完全不可行的。 

有一些微妙的情况打破了粗心的推理。 首先，在两个目标都消失之前从一侧移除并不总是最佳的，因为根据最小值和最大值的位置，最佳策略可能涉及首先从左侧移除或首先从右侧移除或两者的混合。 

例如，如果最小值位于左端附近，最大值位于右端附近，我们可能希望删除每个的较近的一侧。 但如果两者都在同一侧，则仅从该侧移除可能是最佳选择。 

第二种边缘情况是当一个极端已经接近结束但另一个极端位于数组内部时。 在不比较两个方向的情况下从一侧贪婪地移除很容易导致移动次数过多。 

## 方法

 暴力方法会尝试删除左侧或右侧的每个序列，直到最小和最大元素都被删除。 每个状态都由当前子数组定义，并且从每个状态我们分为两种可能性。 这形成了深度高达 n 的二叉树，从而导致 O(2^n) 状态。 即使进行了修剪，结构仍然是指数级的，因为每个决策都会影响两个目标的未来可用性。 

关键的见解是停止考虑序列，而是考虑位置。 唯一重要的是最小和最大元素位于原始数组中的位置。 一旦我们知道它们的索引，问题就相当于从两端收缩数组，直到两个索引都被删除。 

如果我们将最小和最大元素的位置表示为 i 和 j，那么我们只关心需要删除多少次来消除这两个索引。 只有三种有意义的策略。 我们可以从左侧删除，直到两者都消失，从右侧删除，直到两者都消失，或者从两端删除：一些从左边，一些从右边。 

这将问题简化为根据 i 和 j 评估恒定数量的案例。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最佳 | 每次测试 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 扫描数组，找到最小元素的索引和最大元素的索引。 这些位置完全决定了其余的计算，因为所有其他值与去除过程无关。 
2. 设 i 为最小索引，j 为最大索引。 不失一般性，假设 i <= j。 如果没有，请交换它们。 这种规范化避免了以后的案例分割。 
3. 计算三个候选策略。 首先，删除从左边到 i 和 j 中较远的一个的所有内容。 这需要 max(i, j) + 1 次移动，因为我们从零开始索引。 
4. 其次，删除从右边到 i 和 j 中较近的一个的所有内容。 这需要 n - min(i, j) 次移动，因为我们从右侧删除直到两个位置都消失。 
5. 第三，分别删除左侧直至i和右侧直至j的部分。 这需要 (i + 1) + (n - j) 次移动。 这相当于先删除i之前的所有元素，然后删除j之后的所有元素。 
6. 答案是这三个值中的最小值，因为每个值都对应于保证两个目标元素都被删除的有效删除策略。 

### 为什么它有效

 游戏的状态始终是一个连续的子数组，因此任何移动序列都对应于向内缩小边界。 最小和最大元素必须都位于最后剩余线段之外。 因此，任何有效的策略都相当于选择排除这两个指数的最终细分。 到达该段的成本仅取决于从左侧和右侧删除了多少元素，这将问题减少到最小化超出边界位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    mn = min(range(n), key=lambda i: a[i])
    mx = max(range(n), key=lambda i: a[i])
    
    i, j = mn, mx
    if i > j:
        i, j = j, i
    
    # three strategies
    left_only = j + 1
    right_only = n - i
    both = (i + 1) + (n - j)
    
    print(min(left_only, right_only, both))
```该解决方案首先使用线性扫描来识别最小值和最大值的索引。 然后它会标准化它们的顺序，以便最小索引排在第一位。 这允许清晰地制定三种删除策略，而无需进行案例分割。 

第一个策略从左侧移除，直到两个目标中最右侧的目标消失。 第二个从右侧移除，直到最左侧消失。 第三个在两端之间进行分割去除，这对应于隔离仍然不包含两个极端的中间段。 

所有算术都直接统计需要删除多少次，不需要对过程进行模拟。 

## 工作示例

 ### 示例 1

 输入：`[1, 5, 4, 3, 2]`最小值位于索引 0 处，最大值位于索引 1 处。

 | 初始化| 0 | 1 | 2 | 5 | 4 | 2 |

 最好的策略是删除最左边的两次，快速删除 1 和 5。 这表明仅关注一侧可以优于混合删除。 

### 示例 2

 输入：`[2, 1, 3, 4, 5, 6, 8, 7]`最小值位于索引 1，最大值位于索引 6。 

| 步骤| 我| j | 仅左 | 仅右 | 两者 | 答案|
 | --- | --- | --- | --- | --- | --- | --- |

 这里的最佳解决方案是删除直到最小值的前缀和最大值之后的后缀。 这避免了在中间区域浪费动作。 

这两个例子显示了极端聚类和分离极端之间的对比，这正是三例公式所捕捉到的。

import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        right_only = n - i
        both = (i + 1) + (n - j)
        
        out.append(str(min(left_only, right_only, both)))
    
    return "\n".join(out)

 ## 边缘情况

 当最小值和最大值相邻时，答案始终为 2，除非它们已经位于末尾。 用于输入`[2, 1, 3, 4]`、min 和 max 位于索引 1 和 0 处，因此最好的移动是先移除一侧，然后再移除另一侧，共移动 2 次。 

当两个极端已经处于相反的两端时，例如`[1, 2, 3, 4, 5]`，答案变为 2，因为删除任一侧两次都会立即隔离两个目标。 该算法通过以下方式捕获这一点：`both`或无特殊外壳的单面配方。 

当两个极端都在中间时，比如`[3, 1, 5, 2, 4]`，最优策略是从两端拆分移除。 计算出的`both`值正确地反映了只有两个位置之间的间隔之外的元素需要被删除。
