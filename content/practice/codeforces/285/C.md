 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并且允许我们使用单位增量或减量来修改它。 每一次这样的操作都需要花费一次移动。 目标是将数组转换为大小的排列`n`，这意味着我们最终必须得到准确的数字`1`到`n`，各使用一次。 

因此，任务不是重新排列元素，而是更改它们的值，以便在所有调整之后，最终值的多重集变为`{1, 2, ..., n}`。 数组中元素的顺序与最终排列无关，但成本取决于将哪个原始元素移动到哪个目标值。 

关键的困难在于每个元素可以被分配任意目标值`1`到`n`，但每个目标必须仅使用一次。 分配成本`a[i]`重视`x`是`|a[i] - x|`。 我们想要最小的总成本匹配。 

和`n`最多`3 · 10^5`，任何尝试所有分配或使用通用匹配算法的解决方案都太慢。 一个天真的二分匹配解释会建议`O(n^3)`或者至少`O(n^2)`行为，这是不可行的。 

当值远远超出范围时，会出现微妙的边缘情况`[1, n]`。 例如，如果所有`a[i]`非常大，按输入顺序分配的粗心贪婪可能会失败，因为正确的配对取决于全局排序，而不是本地选择。 

另一个边缘情况是重复的`a`。 由于最终数组必须具有不同的值，因此重复项必须在目标之间以最佳方式“分散”，这再次表明本地决策是不够的。 

## 方法

 看待问题的一种直接方法是将其视为分配问题：我们希望匹配每个初始值`a[i]`到一个独特的目标值`p[i]`在`[1, n]`最小化总绝对差。 这是二部图中经典的最小成本完美匹配。 

蛮力方法会尝试所有排列`1..n`并计算每个任务的成本。 这立即变成阶乘时间，大致`O(n!)`，即使对于`n = 10`。 

一种更结构化的暴力改进是将其视为二分匹配问题并应用最小成本流或匈牙利算法。 这给出了正确性，但运行时间约为`O(n^3)`或者`O(n^2 log n)`取决于实施情况，仍然远远超出限制。 

关键的结构见解是两边都在一条线上排序，并且成本是绝对差异的。 在这个一维几何中，最佳分配永远不会交叉。 如果我们想象配对已排序`a`具有排序目标值的值`1..n`，任何交叉分配都可以交换，而不会增加成本。 这将问题从组合匹配问题简化为单调配对问题。 

一旦我们排序`a`，最优策略变为配对最小的`a`和`1`，第二小的`2`， 等等。 这是有效的，因为成本函数`|a - b|`在一条线上保留了非交叉的最优结构。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 | O(n!) | O(n) | 太慢了 |
 | 匈牙利/最小成本流程| O(n^3) | O(n^3) | O(n^2) | O(n^2) | 太慢了 |
 | 排序+贪心匹配| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对数组进行排序`a`按非递减顺序。 这沿着数轴对齐元素，这样我们就可以推断出单调配对。 
2. 对于每个位置`i`从`1`到`n`, 指定目标值`i`到`a[i]`在已排序的数组中。 这强制与排列进行一对一映射`{1..n}`。 
3. 将总成本累加为`|a[i] - i|`对于所有职位。 每一项代表将该元素移动到其分配的排列值所需的最小移动。 
4. 输出总和。 

关键的一步是第二步：我们致力于按顺序配对，这避免了分配之间的任何交叉。 

### 为什么它有效

 考虑任意两个元素`a[i] ≤ a[j]`和两个目标值`x < y`。 如果我们分配`a[i]`到`y`和`a[j]`到`x`，总成本为`|a[i] - y| + |a[j] - x|`。 交换分配收益`|a[i] - x| + |a[j] - y|`。 在实际生产线上，交换不会增加成本，而且常常会降低成本。 重复应用此参数可以消除分配之间的所有反转，从而强制实现尊重排序顺序的最佳解决方案。 因此排序后的贪婪配对是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

a.sort()

ans = 0
for i in range(n):
    ans += abs(a[i] - (i + 1))

print(ans)
```排序步骤至关重要，因为它建立了最佳配对所需的单调结构。 无需排序、配对`a[i]`和`i+1`将是任意且不正确的。 

该循环计算将每个元素转换为其分配的排列值的确切成本。 使用`i + 1`反映排列是 1 索引的。

 ## 边缘情况

 关键的边缘情况是所有值都相同。 对于输入：```
4
5 5 5 5
```排序什么都不做，目标是`1,2,3,4`。 该算法分配成本`4 + 3 + 2 + 1 = 10`。 每个元素独立地移向其分配的槽，并且不会发生冲突，因为唯一性是由目标端强制执行的。 

另一种边缘情况是当值已经是排列但颠倒时：```
3
3 2 1
```排序后我们得到`[1,2,3]`，并且所有成本为零。 这表明正确性取决于排序配对，而不是原始位置。 

第三种情况是超出范围的极值：```
3
100 100 100
```排序后的数组是相同的，并且与`1,2,3`产出总成本`294`。 该算法仍然有效，因为成本纯粹是沿着数轴的位置，与大小无关。
