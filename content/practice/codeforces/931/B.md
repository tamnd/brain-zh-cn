 ## 解决方案
 ## 问题理解

 我们有一场单败淘汰赛$n$团队标记为从 1 到$n$。 比赛的结构是固定且机械的：在每一轮中，剩余的球队按照原来的标签排序，然后连续配对，因此1队对阵2队，3队对阵4队，依此类推。 胜者晋级，败者离开，同样的过程不断重复，直到只剩下两支球队，然后进行最后的比赛。 

问题不是模拟获胜者或预测冠军。 相反，我们被告知两个特定的团队$a$和$b$，我们想知道他们最早可能在哪一轮相遇，假设结果可以自由选择，只要它们与配对结构一致。 如果他们只在锦标赛的最后一场比赛中相遇，我们输出“Final!”，否则我们输出轮次索引。 

约束条件$n \le 256$足够小，甚至重复模拟或重复区间推理也是可行的。 由于每轮将队伍数量减半，因此总轮数最多为 8 轮，因此任意$O(n \log n)$甚至$O(n \log^2 n)$推理是微不足道的。 

主要的微妙之处在于，对决纯粹是通过每轮后的排序来确定的。 这意味着两支球队在给定的一轮中相遇，在反复折叠括号结构后，他们在该级别落入同一相邻对中。 

一个常见的错误是仅模拟前向淘汰或尝试贪婪地分配获胜者。 但这种做法失败了，因为问题不在于单一的锦标赛结果，而在于是否存在某种结果可以让两支球队生存下来直到配对。 

第二个微妙的失败案例是假设他们的会议回合仅取决于他们的初始距离。 这是不正确的，因为获胜者在每轮压缩后都会重新调整位置，因此邻接关系是根据块结构而不是固定索引而演变的。 

## 方法

 暴力解释是模拟比赛的所有可能结果并跟踪是否$a$和$b$每轮都可以配对。 这将涉及考虑每轮每场比赛的两个可能的获胜者。 第 1 轮中有$n/2$匹配，每个都有 2 个选择，所以$2^{n/2}$可能性已经存在，而且这种可能性在各轮中呈指数级爆炸。 即使是为了$n = 16$，这变得很棘手。 

关键的观察是我们永远不需要真正的赢家。 重要的只是是否$a$和$b$可以在锦标赛括号结构的同一部分中保留足够长的时间以满足满足要求。 

在任何一轮中，锦标赛都会有效地将当前集合划分为大小连续的块$2^k$在一轮$k$，因为每一轮都会将球队数量减半并保留获胜者的顺序。 当两个玩家在某一轮中在重复减半后在大小为 2 的同一相邻区块中配对时，他们就会相遇。 

因此，我们不是模拟消除，而是将它们的位置模拟为间隔：每轮通过除以 2 来压缩索引。如果两个索引仅在最低有效位上不同，则它们在该轮中相遇。 

同样，如果我们在 1 索引序列中跟踪它们的当前位置，则每一轮都会替换索引$x$和$\lceil x/2 \rceil$。 我们重复直到两个值相等。 他们变得平等的第一轮是他们相遇的轮。 如果在最后阶段双方相等，则相当于“决赛！”。 

这将指数过程转变为对数过程。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（模拟所有结果）|$O(2^n)$|$O(n)$| 太慢了 |
 | 最佳（每轮索引压缩）|$O(\log n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们将每一轮解释为通过配对连续索引来缩小锦标赛规模。 

1. 从职位入手$a$和$b$如所给出的。 

这些代表了两支球队在本轮比赛中的排名。 
2. Initialize a round counter starting at 0.

 该计数器跟踪我们应用了多少次压缩。 
3.同时$a \neq b$，通过将每个位置映射到来更新两个位置$\lceil x/2 \rceil$。 

此步骤模拟获胜者成对晋级：(1,2) 变为 1，(3,4) 变为 2，依此类推。 
4. 每次压缩后增加循环计数器。 

每个增量对应于在锦标赛中深入一轮。 
5. 停止时$a = b$。 此时，两队属于同一比赛区块。 
6. 如果这种情况发生在最后可能的级别，只剩下两支球队，则输出“Final!”，否则输出回合索引。 

关键思想是每次压缩都会保留相对的锦标赛结构，因此两个索引第一次折叠到同一块时恰好对应于最早可能的会议回合。 

### 为什么它有效

 在每一轮比赛中，球队都会根据当前的顺序分组。 这种顺序保留在获胜者中，这意味着唯一重要的是一支球队属于哪对组合。 转变$x \to \lceil x/2 \rceil$正是锦标赛树中从位置到其父块的映射。 

当两支球队进入同一个区块时，他们会在同一区块中相遇，而该区块对应于一场比赛配对。 第一个这样的级别是独特的，因为每次压缩都会严格降低位置分辨率，同时保留分组结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    
    round_num = 0
    
    while a != b:
        a = (a + 1) // 2
        b = (b + 1) // 2
        round_num += 1
    
    # determine if final round
    # number of rounds is log2(n), final happens when only 2 teams remain
    # if they meet at last compression, it's final
    if (1 << round_num) == n:
        print("Final!")
    else:
        print(round_num)

if __name__ == "__main__":
    solve()
```该实现直接应用了每轮将团队索引映射到其父配对索引的思想。 表达式`(a + 1) // 2`是一种紧凑的计算方式$\lceil a/2 \rceil$，它精确地模拟了配对结构。 

循环继续，直到两队陷入该隐式锦标赛树中的同一节点。 所采取的步骤数是它们在括号结构中首次兼容的回合。 

最终条件检查这次会议是否发生在锦标赛树的最后可能级别，即只剩下两支球队。 这对应于支架的完整深度，即$\log_2(n)$考虑到问题的限制。

 ## 边缘情况

 一种边缘情况是当$a$和$b$在第一轮中已经相邻。 用于输入`4 1 2`，两者处于相同的初始配对中，因此循环运行一次并返回 1，正确匹配第一轮。 

另一种情况是当它们位于支架的两端时，例如`8 1 8`。 压缩顺序表明它们仅在最后阶段相遇，因为两者都穿过锦标赛树的对称半部分，直到在根处收敛。 

第三种情况是当他们在不同的本地对中但仍然很早就见面时，例如`8 2 3`。 一次压缩后，两者都映射到同一父块，因此它们在第 1 轮中相遇。这表明压缩后的邻接关系（而不是初始邻接关系）决定了相遇时间。
