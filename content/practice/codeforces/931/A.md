 ## 解决方案
 ## 问题理解

 两个人站在整数坐标的数轴上$a$和$b$。 他们希望最终位于相同的整数位置，并且每个人都可以向左或向右移动一步任意次数。 

不同的是，移动成本不是线性的。 如果一个人使$k$总移动量，他们的疲劳程度是$1 + 2 + \dots + k$，等于$k(k+1)/2$。 动作的顺序并不重要，重要的是一个人总共走了多少步。 

任务是选择一个集合点$x$，将两个人移至$x$，并最小化他们的疲劳值的总和。 

限制非常小，头寸最多为 1000 个。这立即表明，即使是$O(n)$或者$O(n^2)$扫描所有可能的交汇点是可行的，无需考虑性能。 真正的困难不是计算，而是认识移动成本的行为方式。 

这里的一个天真的错误是假设由于两者都可以自由移动，所以答案仅取决于一些类似中点的行为。 另一个错误是认为方向很重要。 事实并非如此，因为向左或向右移动具有相同的成本结构，只有步数很重要。 

一个微妙的边缘情况是当两者相交时远离两个初始点。 即使两人都移动，与只有一个人移动相比，它可能仍然是最佳选择，因为分开距离可以减少成本的二次增长。 

## 方法

 直接的方法是尝试每一个可能的会面位置$x$。 对于每个$x$，计算每个人必须移动多远：$|a-x|$和$|b-x|$。 如果一个人动了$d$步骤，它们的成本是$d(d+1)/2$。 将两项成本相加即可得出该会面点的总疲劳度。 

自从$a$和$b$最多 1000 个，有效的交汇点也在它们周围的小范围内。 外任意一点$[\min(a,b), \max(a,b)]$只能同时增加两个距离，并不能改善解。 

蛮力方法检查所有候选者$x$在此区间内，计算成本并取最小值。 这是正确的，因为问题简化为整数点上的一维凸搜索。 

关键的见解是成本函数在距离上是二次的，因此虽然每个单独的成本增长速度快于线性，但两个代理的总和仍然在整数线上形成一个简单的单峰函数。 这保证了最小值出现在之间的段附近$a$和$b$，并且对该小区域进行详尽的检查就足够了。

 ## 算法演练

 1.读取两个整数$a$和$b$，代表两个朋友的起始位置。 我们将评估整数线上可能的交汇点。 
2. 将搜索范围计算为之间的所有整数点$\min(a,b)$和$\max(a,b)$。 任何最佳的集合点都必须位于这个区间内，因为向外移动会同时增加两个距离。 
3. 用一个非常大的数字初始化一个答案变量。 这将跟踪在所有候选人会面点观察到的最低总疲劳度。 
4. 迭代每个整数点$x$在选定的范围内。 每个$x$被视为潜在的会议地点。 
5. 对于每个$x$，计算每个朋友必须行驶的距离：$d_1 = |a-x|$和$d_2 = |b-x|$。 这些距离完全决定了疲劳程度。 
6.使用三角数公式将每个距离转换为疲劳度$d(d+1)/2$，然后将两个值相加。 这给出了会议的总费用$x$。 
7. 使用所有计算值中的最小值更新答案。 
8.输出最终的最小疲劳度。 

### 为什么它有效

 对于任何固定的集合点，每个参与者的成本仅取决于他们采取的步数，而不是路径。 由于成本严格增加且距离凸出，因此将运动分散到远离之间的段$a$和$b$永远不会同时帮助两者。 因此，最优解必须位于连接两个起点的区间内。 彻底检查该有界区域中的所有整数点可保证找到全局最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def cost(d):
    return d * (d + 1) // 2

a = int(input())
b = int(input())

lo = min(a, b)
hi = max(a, b)

ans = float('inf')

for x in range(lo, hi + 1):
    total = cost(abs(a - x)) + cost(abs(b - x))
    ans = min(ans, total)

print(ans)
```功能`cost`对三角数公式进行编码，这是计算中唯一的非线性部分。 该循环会考虑每个可行的会面点并评估双方参与者的确切成本。 

使用`min(a,b)`和`max(a,b)`避免在两个距离一起增加的段之外进行不必要的检查，这只会产生更糟糕的结果。

 ## 边缘情况

 一个关键的边缘情况是当两个朋友都已经很亲密的时候。 对于输入：```
3
4
```该算法仅检查$x=3$和$x=4$。 在$x=3$，成本为$0$和$1$， 全部的$1$。 在$x=4$，对称结果$1$。 该循环确保考虑两个端点，因此不会由于差一范围误差而错过最佳值。 

另一个重要的情况是最佳交汇点严格位于两个位置之间。 为了：```
1
5
```该循环评估从 1 到 5 的所有点，包括$x=3$，其中成本是$3$和$3$。 总和$6$被正确识别为最小值。 这证实将搜索限制在段内就足够了，不需要外部点。
