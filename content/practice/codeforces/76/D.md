 ## 解决方案
 ## 问题理解

 给定两个非负整数，`A`和`B`。 我们需要构造另外两个非负整数，`X`和`Y`，这样：

 - 它们的总和等于`A`- 他们的按位异或等于`B`在所有有效对中，我们必须输出尽可能最小的一个`X`。 

有趣的部分是加法和异或通过进位相互作用。 如果我们只看异或，每个位的行为都是独立的。 加法是不同的，因为来自较低位的进位会改变下一位。 整个问题实际上是关于理解这两个操作如何结合在一起。 

数字可以大到`2^64 - 1`，所以对所有可能的值进行暴力破解是不可能的。 甚至迭代所有候选者`X`最多需要`2^64`的操作，这是完全不可行的。 我们需要的东西能够在大致恒定的时间内工作，或者在最坏的情况下与位数成正比。 由于 64 位整数只有 64 个位置，因此`O(64)`解决方案实际上是即时的。 

一些边缘情况很容易被错误处理。 

考虑：```
A = 5
B = 6
```我们知道：```
X + Y >= X xor Y
```因为进位增加了总和。 这里`B > A`，所以不存在解。 仅操作位而不检查可行性的粗心实现可能会错误地产生负中间值。 

另一个微妙的情况是奇偶校验不匹配：```
A = 10
B = 3
```使用身份：```
A = (X xor Y) + 2 * (X & Y)
```我们得到：```
A - B = 7
```这很奇怪。 自从`2 * (X & Y)`必须始终是均匀的，这是不可能的。 缺少此奇偶校验条件会导致错误的答案。 

还有重叠条件：```
A = 2
B = 2
```然后：```
(A - B) / 2 = 0
```这是有效的，给出：```
X = 0
Y = 2
```但对于：```
A = 10
B = 8
```我们得到：```
C = (A - B) / 2 = 1
```现在`C & B = 0`，所以施工工作。 

与以下内容进行比较：```
A = 14
B = 10
```然后：```
C = 2
B = 1010
C = 0010
```它们在位 1 上重叠。这意味着一位需要同时创建进位并进行异或运算，这是不可能的。 简单的重建可能会在这里默默地生成无效数字。 

## 方法

 最直接的暴力想法是尝试每一个可能的值`X`，计算：```
Y = A - X
```并检查是否：```
X xor Y == B
```这是正确的，因为每个有效对都必须满足该方程。 问题在于搜索空间。 自从`A`可以接近`2^64`，暴力方法可能需要大约`10^19`迭代。 即使每秒十亿次操作也需要几个世纪的时间。 

关键的观察结果来自涉及 sum 和 xor 的标准恒等式：$X+Y=(X\oplus Y)+2(X\&Y)$异或计算位不同的位置。 这`AND`计算两个位所在的位置`1`，在加法过程中创建进位。 每个进位将其位值的两倍贡献给最终的和。 

自从`B = X xor Y`，我们可以重写：```
A = B + 2 * (X & Y)
```让：```
C = X & Y = (A - B) / 2
```现在问题变成：

 - 构造两个数字，其异或为`B`- 谁和是`C`在每一位：

 - 如果有点`B`是`1`，那么位`X`和`Y`必须不同
 - 如果有点`C`是`1`，那么两位必须是`1`这两个条件不能同时发生在同一个位上。 所以：```
B & C == 0
```必须持有。 

一旦满足这个条件，重建就变得容易了：

 - 每个`1`一点`C`进入两个数字
 - 每个`1`一点`B`必须恰好输入其中一个数字

 尽量减少`X`，我们将所有仅异或位分配给`Y`而不是`X`。 

这给出：```
X = C
Y = C + B
```前提是重叠条件有效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^64) | O(1) | O(1) | 太慢了 |
 | 最佳| 奥(64) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`A`和`B`。 
2. 检查是否`A < B`。 

自从：```
X + Y >= X xor Y
```总和永远不能小于异或。 
3. 计算：```
D = A - B
```如果`D`很奇怪，不存在解。 

数量：```
D = 2 * (X & Y)
```必须始终是均匀的。 
4. 计算：```
C = D // 2
```这代表了常见的`1`两个数字共享的位。 
5. 检查是否：```
C & B != 0
```如果发生这种情况，输出`-1`。 

一个位不能同时属于异或和进位结构。 异或位要求两个数字不同，而与位要求两者相同`1`。 
6. 构造答案：```
X = C
Y = C + B
```所有共享位都保留在内部`C`。 所有不同的位`B`被分配给`Y`保留`X`尽可能小。 
7. 输出`X`和`Y`。 

### 为什么它有效

 该构造基于二进制加法到异或和进位的精确分解：```
X + Y = (X xor Y) + 2 * (X & Y)
```价值`C = (A - B) / 2`唯一地确定所有产生进位的位。 如果任何位同时属于两者`B`和`C`，我们需要相同的位位置来同时区分和匹配，这是不可能的。 

什么时候`B & C == 0`，位的角色是完全分开的：

 - 一点点`C`是`1`在两个数字中
 - 一点点`B`是`1`正好是一个数字

 将每个仅异或位分配给`Y`最小化`X`，因为将这些位中的任何一个添加到`X`只会增加它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

A = int(input())
B = int(input())

if A < B:
    print(-1)
    sys.exit()

D = A - B

if D % 2:
    print(-1)
    sys.exit()

C = D // 2

if C & B:
    print(-1)
    sys.exit()

X = C
Y = C + B

print(X, Y)
```第一个条件检查 sum 和 xor 之间的基本不等式。 任何有效对必须满足：```
X + Y >= X xor Y
```因为进位只会增加总和。 

接下来，代码计算`D = A - B`。 该值必须等于共享位结构的两倍：```
D = 2 * (X & Y)
```如果`D`很奇怪，重建是不可能的。 

重叠检查：```
if C & B:
```是核心正确性条件。 设定位`C`意味着两个数字都包含`1`那里。 设定位`B`意味着那里的数字不同。 一位位置不能同时满足这两个要求。 

最终的结构是故意不对称的：```
X = C
Y = C + B
```每个仅异或位都进入`Y`，这保持了`X`最小。 使用加法而不是按位或是安全的，因为`C`和`B`永不重叠。 

Python 整数自动安全地处理 64 位值，因此不存在溢出风险。

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    A = int(input())
    B = int(input())

    if A < B:
        print(-1)
        return

    D = A - B

    if D % 2:
        print(-1)
        return

    C = D // 2

    if C & B:
        print(-1)
        return

    print(C, C + B)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue().strip()

 ## 边缘情况

 考虑：```
A = 5
B = 6
```该算法首先检查：```
A < B
```这是真的。 由于异或永远不会超过总和，因此该算法正确打印：```
-1
```而不尝试重建。 

现在考虑：```
A = 10
B = 3
```该算法计算：```
D = 10 - 3 = 7
```自从`7`是奇数，不可能：```
D = 2 * (X & Y)
```该算法立即终止`-1`。 

最后，考虑重叠冲突：```
A = 14
B = 10
```我们计算：```
D = 4
C = 2
```二进制：```
B = 1010
C = 0010
```现在：```
C & B = 0010
```这是非零的。 

位 1 需要是：

 - 之间不同`X`和`Y`因为它属于异或
 - 等于`1`在两个数字中，因为它属于 和

 这种矛盾使得实例不可能，并且算法正确地输出`-1`。
