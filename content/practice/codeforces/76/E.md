 ## 解决方案
 ## 问题理解

 我们在 2D 平面上最多有十万个点。 对于每对无序点，我们必须计算它们之间的欧氏距离平方并将所有这些值加在一起。 

对于两点`(x1, y1)`和`(x2, y2)`，距离的平方为$(x_1-x_2)^2 + (y_1-y_2)^2$该任务并不要求实际的欧几里德距离，只要求其平方。 这很重要，因为平方距离可以扩展为可以有效求和的代数表达式。 

输入大小立即排除成对枚举。 和`N = 100000`，对的数量约为$\frac{N(N-1)}{2}$最坏的情况下大约有 50 亿对。 即使每对的工作量很小，也会超出时间限制。 

坐标本身很小，介于`-10000`和`10000`，但这不足以证明任何二次解的合理性。 正确的方法必须运行接近线性时间。 

有几种容易被忽略的边缘情况。 

如果多个点重合，则它们的贡献应为零。 例如：```
3
1 1
1 1
1 1
```每对都有距离`0`，所以答案是：```
0
```假设所有点都是不同的，粗心的实现可能会意外地重复计算或错误处理重复项。 

负坐标也很重要，因为像这样的术语`(x1 - x2)^2`平方后保持正值。 例如：```
2
-3 -4
3 4
```距离的平方为：```
(6)^2 + (8)^2 = 100
```任何依赖绝对值而不仔细平方的方法都可能产生不正确的结果。 

另一个微妙的问题是具有固定大小整数的语言中的整数溢出。 假设所有坐标都接近`10000`和`N`很大。 最终答案可能会变得非常大，远远超出 32 位整数范围。 Python 会自动处理这个问题，但在 C++ 中这需要`long long`。 

## 方法

 蛮力方法很简单。 迭代每对点，直接计算平方距离，并将其添加到答案中。 

这意味着评估：$(x_i-x_j)^2 + (y_i-y_j)^2$对于每一个`i < j`。 

这是有效的，因为它与问题定义完全匹配。 问题在于规模。 和`100000`点，大约有五十亿对，每对都需要多次算术运算。 对于一秒的限制来说这太慢了。 

关键的观察结果是 x 和 y 坐标在平方距离公式内是独立的。 将表达式展开可得：$(x_i-x_j)^2 = x_i^2 + x_j^2 - 2x_ix_j$y 坐标也类似。 

因此，我们可以考虑每个坐标对最终总和的贡献次数，而不是从几何角度考虑对。 

首先只考虑 x 部分：$\sum_{i<j}(x_i-x_j)^2$展开所有术语：$\sum_{i<j}(x_i^2+x_j^2-2x_ix_j)$每一个`x_i^2`准确地出现`N-1`所有对的时间。 交叉项可以使用总和的平方重写：$\left(\sum x_i\right)^2 = \sum x_i^2 + 2\sum_{i<j}x_ix_j$重新排列给出：$\sum_{i<j}(x_i-x_j)^2 = N\sum x_i^2 - \left(\sum x_i\right)^2$相同的公式独立适用于 y 坐标。 

这将问题从成对计算转变为仅维护四个聚合值：```
sum_x
sum_y
sum_x2
sum_y2
```读完所有点后，我们可以直接计算答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N²) | O(1) | O(1) | 太慢了 |
 | 最佳| O(N) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取点数`N`。 
2. 初始化四个累加器：`sum_x`,`sum_y`,`sum_x2`， 和`sum_y2`。 
3. 对于每个点`(x, y)`:

 1.添加`x`到`sum_x`。 
2.添加`y`到`sum_y`。 
3.添加`x * x`到`sum_x2`。 
4. 添加`y * y`到`sum_y2`。 

这些值就足够了，因为最终公式仅取决于总和和平方和。 
4. 计算 x 坐标的总贡献：$N\sum x_i^2 - \left(\sum x_i\right)^2$1. 计算 y 坐标的总贡献：$N\sum y_i^2 - \left(\sum y_i\right)^2$1. 将两个贡献相加并打印结果。 

### 为什么它有效

 该算法依赖于平方差的代数展开。 每个成对的平方距离都可以分解为独立的 x 和 y 分量。 当所有扩展项相加时，二次对结构会分解为仅涉及全局和和平方和的表达式。 

身份$\sum_{i<j}(a_i-a_j)^2 = N\sum a_i^2 - \left(\sum a_i\right)^2$对于任何数字序列都成立。 将其分别应用于 x 坐标和 y 坐标可以精确地重建所有对的距离平方和的总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    sum_x = 0
    sum_y = 0
    sum_x2 = 0
    sum_y2 = 0

    for _ in range(n):
        x, y = map(int, input().split())

        sum_x += x
        sum_y += y

        sum_x2 += x * x
        sum_y2 += y * y

    ans = n * sum_x2 - sum_x * sum_x
    ans += n * sum_y2 - sum_y * sum_y

    print(ans)

solve()
```代码的第一部分读取所有点，同时维护四个聚合值。 我们从不存储分数本身，因为最终公式仅取决于总数。 

表达式`x * x`和`y * y`直接计算平方坐标。 在竞争性编程代码中，使用乘法而不是求幂稍微更快、更清晰。 

最终的计算准确地反映了数学推导。 首先我们计算总的 x 贡献，然后计算 y 贡献，最后将它们加在一起。 

一个微妙的点是，该公式已经对每个无序对精确计数一次。 在实现的任何地方都没有除以二，因为代数恒等式已经正确地说明了对计数。 

Python 整数自动扩展到任意精度，因此溢出不是这里的问题。

 ## 边缘情况

 考虑所有点都相同的情况：```
3
2 2
2 2
2 2
```加工过程中：

 | 点| 总和_x | 总和 | 总和_x2 | 总和_y2 |
 | --- | --- | --- | --- | --- |
 | (2,2) | 2 | 2 | 4 | 4 |
 | (2,2) | 4 | 4 | 8 | 8 |
 | (2,2) | 6 | 6 | 12 | 12 12 | 12

 现在计算：```
3 * 12 - 6² = 36 - 36 = 0
```对于两个坐标，所以总答案是`0`。 

这是有效的，因为相同的坐标使得平方和项完全抵消了乘积平方和项。 

现在考虑负坐标：```
2
-3 -4
3 4
```累加器变为：

 | 点| 总和_x | 总和 | 总和_x2 | 总和_y2 |
 | --- | --- | --- | --- | --- |
 | (-3,-4) | (-3,-4) | -3 | -4 | 9 | 16 | 16
 | (3,4) | 0 | 0 | 18 | 18 32 | 32

 最终计算：```
2 * 18 - 0² = 36
2 * 32 - 0² = 64
```全部的：```
36 + 64 = 100
```平方自然地去除了符号，与几何距离公式完全匹配。 

最后，考虑最小的可能输入：```
1
5 7
```根本没有成对的。 该公式仍然正确运行：```
1 * 25 - 5² = 0
1 * 49 - 7² = 0
```所以答案就变成了`0`无需任何特殊情况处理。
