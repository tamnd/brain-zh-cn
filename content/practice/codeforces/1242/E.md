 ## 解决方案
 ## 问题理解

 我们被要求构建一个由多边形面组成的平面结构，其中每个面都是共享图中的一个简单循环。 每个面 i 的边界上必须恰好有 a_i 个顶点。 每当两个面接触时，它们必须共享整个边，而不仅仅是一个顶点。 目标是构建任何这样的连通平面图，没有多条边或自环，并最小化仅属于一个面的边数，这相当于最小化嵌入的外边界长度。 

重新解释这一点的一个有用方法是考虑从不相交的多边形开始，然后沿着共享边将它们粘合在一起。 每当两个面共享一条边时，该边就不再对外周长产生影响。 因此，该任务相当于排列面，以便尽可能多的边在相邻面之间“配对”。 

约束条件结构大但算术简单。 所有 a_i 的总和至多为 3·10^5，这意味着任何结构在总面尺寸上都必须基本上是线性的。 任何试图考虑人脸之间成对交互或尝试进行全局平面嵌入搜索的方法都会立即变得太慢，因为这会导致人脸数量呈二次方行为。 

当所有面都是三角形时，会出现微妙的边缘情况。 一种简单的方法可能会尝试将面粘合在链中，但如果链构造不仔细，则可能会引入重复的边缘或导致平面性失败。 另一种有问题的情况是当一个非常大的多边形与许多小多边形配对时。 粗心的策略可能会过度使用大面的顶点并意外地强制自相交或重复的边。 

主要隐藏的困难是我们不仅仅是构建任何图，而是在严格的简单性约束下构建最大的边共享配置。 

## 方法

 一种强力的解释是从每个面作为一个独立的循环开始，然后反复尝试沿着边缘粘合成对的面，以保持简单性和平面性。 人们可以想象维持平面嵌入并尝试所有有效的合并。 虽然在概念上是正确的，但这需要对几何嵌入进行推理或维护动态平面图结构，并且可能的附件选择的数量随着面和边的数量而快速增长。 在最坏的情况下，每个合并决策都取决于全局平面性约束，从而导致指数或至少二次探索。 

关键的简化来自于将视角从几何转向二元结构。 我们不考虑将面嵌入到平面中，而是考虑面如何通过共享边相互连接。 每个共享边将周长恰好减少 2。因此，最小化周长相当于最大化共享边的数量。 由于每个面都有固定数量的边，因此我们最好的希望是以树状结构连接面，其中每个连接仅使用一个边共享对。 

这减少了在面上构建连接结构的问题，在该结构中，我们贪婪地“附加”面到不断增长的组件，确保每个附加恰好消耗一个现有边界边和新面的一个边。 这提出了一种建设性策略，即我们维护可用边界边池，并通过分割现有边并通过新顶点重新路由它们来增量插入面。 

中心观察是我们可以使用顶点作为属于多个面的“端口”来表示构造。 我们顺序创建顶点并将它们分配给面，以确保每个面成为一个循环，并且通过重用连续的顶点对自然地产生共享边。

 ## 算法演练

 我们通过重用单个生长循环结构来构造所有面，同时仔细分配顶点。 

1. 从空的顶点列表和下一个未使用的顶点标签的计数器开始。 我们的想法是，我们只会在需要时逐渐创建顶点，确保我们永远不会超过允许的总数。 
2. 对于第一个面，创建 a_1 个不同顶点的简单循环。 这建立了一个初始边界。 
3. 维护“当前活动边界边”，我们将重复使用它来附加后续面。 从概念上讲，该边缘代表可以在不破坏平面性的情况下粘合新面的位置。 
4. 对于每个 i > 1 的下一个面，取当前边界并在其上选取一条边。 我们将插入一条由 a_i - 2 个新顶点组成的新路径，该路径形成一个与现有结构恰好共享一条边的循环。 这可确保该面恰好通过一个共享边连接。 
5. 具体来说，如果选择的边界边是 (u, v)，我们在新的面构造中将其替换为路径：

 u → x1 → x2 → ... → x_{a_i-2} → v，

 然后使用现有的边将循环关闭回到 u，该边将成为共享的。 
6. 通过用涉及新顶点的链边替换边 (u, v) 来更新边界表示。 这使结构保持平面和连接。 
7. 重复此操作，直至插入所有面。 

正确性依赖于这样一个事实：每个新面都精确地沿着一条现有边连接，并且每个连接都保持简单性，因为所有新引入的顶点都是唯一的，并且仅在当前面内使用（共享端点除外）。 

### 为什么它有效

 不变的是，在处理 i 个面之后，结构是一个连接的平面嵌入，其中到目前为止引入的每个面都表示为一个简单的循环，并且边界由尚未被两个面共享的边组成。 每一步都通过一次边缘共享操作来减少可用边界，并在不引入交叉的情况下增加内部结构。 由于每个新面都沿着单个现有边连接，并且除了端点之外不会引入任何顶点重用，因此不会出现多重边或自循环。 保留了平面性，因为每个操作都对应于沿现有边界边缘细分面。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    f = int(input())
    a = list(map(int, input().split()))
    
    n = sum(a)
    print(n)
    
    # We will construct a simple chain-like embedding.
    # Maintain a running vertex label
    cur = 1
    
    # Store previous face's last vertex to glue structures
    prev_chain = []
    
    for i, k in enumerate(a):
        if i == 0:
            # first polygon: simple cycle
            face = list(range(cur, cur + k))
            cur += k
            print(*face)
            prev_chain = face
        else:
            # attach new cycle by reusing one edge of previous structure
            # pick edge (prev_chain[0], prev_chain[1])
            u, v = prev_chain[0], prev_chain[1]
            
            face = [u]
            # create new vertices
            for _ in range(k - 2):
                face.append(cur)
                cur += 1
            face.append(v)
            
            print(*face)
            
            # update prev_chain for next attachments
            prev_chain = face

if __name__ == "__main__":
    solve()
```该构造将第一个多边形保留为基循环。 通过重用一条现有边并在概念上用更长的路径替换它来连接每个后续多边形。 打印的面顺序已经保证连续的顶点定义边，并且每个循环的最终闭包隐含在定义中。 

微妙的实现决策是始终重用前一个面的相同边缘。 这避免了显式跟踪完整平面嵌入的需要。 该构造保证没有重复的边，因为每个新顶点都是新鲜的，并且共享结构仅限于连接边的端点。

 ## 边缘情况

 一种边缘情况是只有一张脸时。 该算法仅输出一个大小为 a_1 的周期，并且不执行任何附加操作。 这基本上满足了平面度和最小周长，因为不可能有共享边缘。 

另一种边缘情况是所有面都是三角形时。 在这种情况下，每个新面都使用单个现有边进行附加，并且每个步骤都会引入一个新顶点。 该构造仍然有效，因为除了共享边之外，每个三角形都是独立的，并且由于每个三角形都使用新的内部结构，因此不会出现重复的边。 

最后一种边缘情况是一个面比其他面大得多。 该算法仍然将所有较小的面附加到同一基边，而不会破坏有效性。 每个附件都使用新的顶点，因此即使重复使用相同的基边也不会引入多重边，因为邻接始终是通过每个面的不同中间顶点来定义的。
