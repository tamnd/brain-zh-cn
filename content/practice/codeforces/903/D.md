 ## 解决方案
 ## 问题理解

 我们得到一个最多包含 200000 个整数的数组。 对于每对位置$(i,j)$和$i\le j$，我们评估一个特殊函数$d(a_i,a_j)$，我们需要所有对的总和。 

该函数的行为与正常差异不同。 如果两个数字最多相差一，则它们的贡献为零。 否则，贡献等于普通差额$a_j-a_i$。 正值和负值都是可能的。 

由于配对顺序仅通过索引起作用，因此我们可以想象从左到右处理数组。 当我们到达位置时$j$, 每个较早的元素$a_i$形成一对结束于$j$。 问题变成：之前的所有数字对当前值贡献有多少？ 

极限$n\le 2\cdot10^5$排除二次算法。 一个简单的双循环将粗略地检查$$\frac{200000\cdot199999}{2}\approx2\cdot10^{10}$$成对，这远远超出了两秒所允许的范围。 解决方案围绕$O(n\log n)$或者$O(n)$是必须的。 

一种微妙的情况来自于数字恰好相差一。 这样的对贡献为零，而不是$\pm1$。 

输入：```
2
5 6
```唯一一对有区别$1$，所以答案是```
0
```使用普通减法的粗心实现会产生$1$。 

另一个陷阱是负贡献。 

输入：```
2
10 1
```两人贡献$1-10=-9$，其绝对值超过一，所以正确答案是```
-9
```将函数视为绝对差将给出$9$，这是不正确的。 

重复值也很特殊。 

输入：```
3
7 7 7
```每对的差异为零，因此所有贡献都消失了，答案是```
0
```仅基于前缀和而不消除禁止差异的公式$0,\pm1$会错误地计算这些对。 

## 方法

 最直接的方法检查每一对$(i,j)$。 对于每一对，我们计算普通差异$a_j-a_i$。 如果它的绝对值最多为 1，我们将其替换为 0。 总结所有这些贡献显然是正确的，因为它遵循字面定义。 

问题是对的数量。 和$n=200000$，大约有二十亿对。 即使极其便宜的操作也无法在时限内处理那么多对。 

为了加快速度，请考虑一个位置$j$。 假设所有先前的元素都是已知的。 暂时忽略特殊规则，早期数字的总贡献等于$$\sum_{i<j}(a_j-a_i) =(j-1)\cdot a_j-\text{prefixSum}.$$如果我们维护所有先前元素的总和，则可以在恒定时间内更新该表达式。 

唯一的问题是，值最多相差 1 的对应该贡献零，而不是它们的普通差异。 这些对已经包含在上面的公式中，因此我们必须减去它们的贡献。 

对于当前值$x$，仅先前出现的$x-1$,$x$， 和$x+1$需要修正。 他们的计数就足够了。 如果有

 -$cnt[x-1]$先前的值等于$x-1$,
 -$cnt[x]$先前的值等于$x$,
 -$cnt[x+1]$先前的值等于$x+1$,

 那么普通公式就加上了$$1\cdot cnt[x-1]+0\cdot cnt[x]-1\cdot cnt[x+1]$$对于那些被禁止的配对。 由于他们的贡献应该为零，因此我们正好减去这个金额。 

哈希表使这些计数按预期可用$O(1)$时间，给出线性解。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 初始化一个哈希图，存储每个值到目前为止出现的次数。 还要维护先前元素和运行答案的总和。 
2. 从左到右处理数组。 当当前值为$x$，首先计算所有早期元素的普通贡献。$$(j-1)\cdot x-\text{prefixSum}$$这等于$x-a_i$超过之前的每个索引。 

1. 找出有多少个之前的值相等$x-1$,$x$， 和$x+1$。 

这些正是其成对差异与$x$最多具有绝对值 1。 

1. 普通公式已经包含了这些对的贡献。 他们在公式中的总贡献是$$cnt[x-1]-cnt[x+1].$$即使在校正之前，具有相同值的对的贡献也为零。 

1. 从当前贡献中减去该数量。 

调整后，所有禁止对的贡献实际上为零。 

1. 将更正的贡献添加到答案中。 
2. 将当前值插入到频率图中并更新前缀和。 
3. 继续，直到处理完所有元素。 

### 为什么它有效

 在每一步中，前缀和公式都会计算当前元素与所有早期元素之间的普通差之和。 唯一违反问题定义的对是那些有差异的对$-1$,$0$， 或者$1$。 此类对只能涉及值$x-1$,$x$， 和$x+1$，他们在普通总和中的总贡献恰好是$cnt[x-1]-cnt[x+1]$。 删除该金额会将普通差和转换为所需的函数。 由于每对在处理其右端点时只出现一次，因此最终答案是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    freq = {}
    prefix_sum = 0
    ans = 0

    for i, x in enumerate(a):
        cur = i * x - prefix_sum

        cur -= freq.get(x - 1, 0)
        cur += freq.get(x + 1, 0)

        ans += cur

        freq[x] = freq.get(x, 0) + 1
        prefix_sum += x

    print(ans)

solve()
```变量`prefix_sum`存储所有先前处理的数字的总和。 对于索引处的元素`i`，表达式`i * x - prefix_sum`计算与每个较早值的普通差之和。 

接下来的两行执行校正。 之前的每一次出现`x-1`贡献了`+1`在普通金额内，因此这些捐款必须消失。 之前的每一次出现`x+1`贡献了`-1`，减去一个负数就变成了一个加法。 

顺序很重要。 在计算当前值的贡献之前，不得将当前值插入到频率图中。 这样做会错误地计算由该元素与其自身组成的对。 

Python 整数自动扩展为任意大小，这是必要的，因为答案可能会超出某些语言中遇到的 64 位限制。

 ## 边缘情况

 考虑两个相差一的连续值。 

输入```
2
100 101
```处理 101 给出普通贡献 1。映射报告出现 100 次，因此校正减去 1 并且添加值变为零。 输出是```
0
```考虑重复值。 

输入```
3
7 7 7
```每一个普通的贡献都等于零。 修正项也为零，因为在普通公式中相同的值已经贡献了零。 答案依然存在```
0
```考虑负贡献。 

输入```
2
10 1
```对于第二个元素，普通贡献是$$1-10=-9.$$0 和 2 之前都没有出现过，因此不进行任何校正。 答案就变成了```
-9
```这证实了该算法保留了差异的符号而不是取绝对值。
