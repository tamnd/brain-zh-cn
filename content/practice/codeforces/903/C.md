 ## 解决方案
 ## 问题理解

 我们有 *n* 个立方体盒子，每个盒子的边长由数组 *a* 指定。 Mishka 希望根据严格的规则将这些盒子嵌套在彼此内部：只有当一个盒子严格小于另一个盒子并且较大的盒子尚未包含另一个盒子时，该盒子才能进入另一个盒子。 目标是最小化可见盒子的数量，这些盒子不包含在任何其他盒子中。 本质上，我们希望创建嵌套框链，其中每个链的长度尽可能长，以便尽可能多的框隐藏在其他框内。 

输入约束允许 *n* 最多 5000。这排除了以穷举方式尝试所有排列或所有成对嵌套的强力方法，因为 *n!* 甚至 *n²* 操作可能接近 2500 万或更高，如果算法不简单且不严格，这在 Python 中对于最坏情况的输入来说太慢了。 每个框的大小最多可达 10⁹，这意味着我们不能依赖索引与大小对应的频率数组，但计算重复项是可行的。 

棘手的边缘情况涉及相同大小的盒子。 例如，考虑`3 3 3`。 没有一个盒子可以进入另一个盒子，因为嵌套需要严格较小的尺寸。 正确的最小可见框数是 3。忽略重复项的简单方法可能会尝试错误地嵌套它们并低估可见框的数量。 另一种微妙的情况是当一种尺寸出现多次时，例如，`1 2 2 2 3`。 我们必须确保嵌套的相同大小的盒子不会超过允许的数量，这相当于将相同大小的盒子视为独立的并计算任何大小的最大频率。 

## 方法

 强力方法会尝试模拟所有可能的嵌套配置。 我们可以尝试对盒子进行排序，然后迭代地尝试将每个盒子放入当前空的任何较大盒子中。 虽然这最终会产生正确的答案，但它需要重复检查每一对，可能是 O(n²)，并管理哪些盒子可以自由地包含其他盒子，这会变得混乱且低效。 对于 5000 个框，这可能会导致大约 2500 万次操作，并且接近 Python 中的时间限制，尤其是频繁的列表操作。 

关键的观察结果是，盒子仅在大小上有所不同，并且嵌套约束完全由大小比较决定。 这将问题简化为计算每种尺寸存在多少个盒子。 每个可见的盒子必须至少与任意大小的最大出现次数一样频繁，因为我们不能嵌套相同的盒子。 如果某个尺寸出现五次，而较大的尺寸出现次数较少，则我们需要至少五个可见的盒子来容纳所有它们，而不违反严格的嵌套规则。 排序和计数频率使我们能够有效地识别这个最大计数。 因此，问题归结为计算每个框大小的频率并取最大计数。 这种见解将可能混乱的模拟转换为干净的 O(n log n) 算法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取盒子的数量 *n* 和盒子大小的数组 *a*。 这设置了用于处理的输入。 
2. 对数组 *a* 进行排序。 排序可确保所有大小相同的盒子都是连续的，并使频率计数变得简单。 
3.初始化一个计数器变量来跟踪当前大小和一个变量的频率`max_count`存储看到的最大频率。 
4. 迭代已排序的数组。 对于每个框，检查它是否与前一个框相同。 如果是，则增加计数器。 如果不同，则将计数器重置为 1。 
5. 更新每个框的计数器后，更新`max_count`如果当前计数器超过它。 这保证了`max_count`始终保持最常见尺寸的频率。 
6.处理完所有盒子后，输出`max_count`作为可见框的最小数量。 这是正确的，因为最大频率决定了由于严格的尺寸要求而不能相互嵌套的盒子的数量。 

为什么它有效：不变的是，对于出现 *k* 次的任何大小，至少 *k* 个盒子必须保持可见，因为没有两个相同的盒子可以嵌套。 排序确保我们连续看到所有相同的框，并且跟踪最大频率保证输出永远不会小于必要的最小值。 没有任何配置可以将可见计数减少到低于此最大频率，因此该解决方案是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
a.sort()

max_count = 0
current_count = 0
prev = None

for size in a:
    if size == prev:
        current_count += 1
    else:
        current_count = 1
        prev = size
    if current_count > max_count:
        max_count = current_count

print(max_count)
```解决方案首先对盒子进行排序，使相同尺寸的相邻。 我们初始化`current_count`计算连续的相同盒子。 每次遇到新尺寸时，我们都会重置`current_count`至 1。`max_count`跟踪最大频率。 排序至关重要，因为它允许我们一次性扫描数组而不会丢失重复项。 当遇到新大小时忘记重置计数器将导致计数过多。 使用单独的变量`prev`比依赖索引算术更安全，索引算术可能会导致差一错误。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 |---|---|---|
 | 时间 | O(n log n) | O(n log n) | 排序在复杂度上占主导地位，后续扫描的时间复杂度为 O(n) |

 对于 n 高达 5000 的情况，O(n log n) 相当于大约 65,000 次操作，这完全在 1 秒的时间限制内。 内存使用量极少，在 256 MB 以内即可轻松容纳。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    max_count = 0
    current_count = 0
    prev = None

    for size in a:
        if size == prev:
            current_count += 1
        else:
            current_count = 1
            prev = size
        if current_count > max_count:
            max_count = current_count
    return str(max_count)

# provided samples
assert run("3\n1 2 3\n") == "1", "sample 1"
assert run("5\n2 2 3 3 3\n") == "3", "sample 2"

# custom cases
assert run("1\n7\n") == "1", "single box"
assert run("4\n5 5 5 5\n") == "4", "all equal boxes"
assert run("6\n1 2 2 1 5 3\n") == "2", "duplicates mixed"
assert run("5\n10 20 10 20 10\n") == "3", "high-low-high pattern"
```| 测试输入| 预期产出 | 它验证了什么 |
 |---|---|---|
 | 1\n7 | 1 1 | 单盒边箱|
 | 4\n5 5 5 5 | 5 5 5 5 4 | 所有盒子均等，无法嵌套 |
 | 6\n1 2 2 1 5 3 | 6 2 | 重复项需要跟踪频率 |
 | 5\n10 20 10 20 10 | 5\n10 20 10 20 10 3 | 确保正确的最大频率处理 |

 ## 边缘情况

 用于输入`3 3 3`，该算法将数组排序为`[3, 3, 3]`。 它将 3 的频率计算为 3。由于没有一个盒子可以嵌套到另一个相同大小的盒子中，因此所有三个盒子都保持可见。 输出正确 3.
