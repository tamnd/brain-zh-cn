 ## 解决方案
 ## 问题理解

 该任务询问 Ivan 是否可以仅使用 3 块鸡块中的一小部分和 7 块鸡块中的大部分购买恰好 _x_ 块鸡块。 每个测试用例指定块的目标数量，并且输出应指示是否可以获得该确切数量作为小部分和大部分的非负组合。 

输入受到限制，最多有 100 个测试用例，并且每个测试用例中的目标块数不超过 100。这意味着我们可以负担每个测试用例具有数千次操作的复杂性算法。 例如，尝试小部分和大部分的所有组合的天真的嵌套循环仍将在时间限制内舒适地运行。 

当目标小于大部分的尺寸时，会出现微妙的边缘情况。 例如，如果 Ivan 想要 5 个块，唯一的选择是一两个小部分，但总和都不等于 5。仅检查目标是否可被 3 或 7 整除的简单实现会对某些数字错误地回答“是”，因此我们必须考虑部分的组合而不是单个倍数。 

## 方法

 蛮力方法迭代所有可能的小部分计数，计算需要被大部分覆盖的剩余块，并检查余数是否能被 7 整除。正式地，对于目标 _x_，人们会尝试 _a = 0_ 到 _a_max = x // 3_，并且对于每个 _a_ 计算 _b = (x - 3_a) / 7*。 如果 _b_ 是非负整数，则答案为“是”。 这是正确的，因为它详尽地测试了所有有效的组合。 最大_x_为100时，每个测试用例最多迭代34次，最多100个测试用例时，总操作次数在3400左右，这是可以接受的。 

更快的方法依赖于贪婪观察：任何数字 _x >= 12_ 始终可以表示为 3 和 7 的组合。 12 以下的数字可以预先计算。 这是可行的，因为一旦我们有足够的块将 3 的倍数与一个或多个 7 组合起来，每个后续数字都可以通过添加额外的 3 来形成。 此观察将每个查询简化为一个简单的检查：_x >= 12_ 或 _x_ 位于一组低于 12 的预先计算的可表示数字中。这将预处理后每个测试用例的解决方案变为 O(1)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(x_max * n) = O(100 * 100) | O(1) | O(1) | 已接受 |
 | 预计算/贪心| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取测试用例的数量_n_。 
2. 对于每个测试用例，读取目标块数_x_。 
3. 如果_x_大于或等于12，则立即打印YES。 这依赖于任何 12 或更高的数字都可以分解为 3 和 7 之和的性质。 
4. 如果 _x < 12_，明确检查它是否可以表示为 3 和 7 的和。 该范围内可表示的数字为 3、6、7、9、10。 
5. 如果 _x_ 可表示，则打印 YES，否则打印 NO。 

为什么有效：不变的是 ≥12 的数字总是可达的，因为重复将 3 添加到已经有 7 的数字可确保覆盖所有后续数字。 对于 12 以下的数字，完整的枚举确认可以表示哪些值。 这保证了算法不会错误地声称不可能的数字是可以实现的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can_buy_chunks(x):
    if x >= 12:
        return True
    return x in {3, 6, 7, 9, 10}

n = int(input())
for _ in range(n):
    x = int(input())
    print("YES" if can_buy_chunks(x) else "NO")
```功能`can_buy_chunks`封装了核心逻辑。 检查`x >= 12`捕捉对大数的贪婪洞察力。 对于较小的数字，使用集合可确保 O(1) 成员资格测试。 使用快速 I/O 是因为`input()`有效地读取每一行。 边缘情况（例如 _x = 1_ 或 _x = 2_）会正确返回 NO，因为它们无法表达。

 ## 边缘情况

 对于最小可能目标 _x = 1_ 或 _x = 2_，算法正确返回 NO。 当 _x = 3_ 或 _x = 7_ 时，算法将它们分别识别为从小部分和大部分可到达。 对于 12 及以上的目标，算法会立即打印 YES，这依赖于通过将足够的 3 的倍数添加到包括 7 的基本组合中可以形成任何组合的属性。这确保了 1 到 100 的整个输入范围的正确性。
