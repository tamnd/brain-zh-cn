 ## 解决方案
 ## 问题理解

 我们得到了一份参与者分数列表，我们需要计算有多少种不同的方式可以选择一组参与者在特定的规则下获得文凭。 

通过选择分数阈值来确定有效组。 一旦包含某个分数的参与者，则也必须包含分数大于或等于该分数的每个参与者。 这意味着所选择的集合完全由截止值决定：选择高于或等于它的所有内容，排除低于它的所有内容。 还有一项附加限制，即得分为零的参与者永远不能包含在任何有效组中。 此外，所选组不能为空。 

输入只是分数列表。 输出是可以形成的不同有效组的数量。 

限制很小，参与者最多为 100 名，因此即使是二次或基于排序的解决方案也很容易足够快。 这是一个信号，表明我们应该专注于结构推理而不是优化技巧。 

当存在零时，会出现微妙的边缘情况。 计算所有不同分数阈值而不分隔零的简单方法将错误地包括零分参与者成为所选后缀一部分的配置。 另一个边缘情况是所有非零分数都相等。 在这种情况下，只有一个有效的选择存在，尽管如果我们机械地考虑分割排序值，有很多方法可以选择阈值。 

例如，考虑输入：```
5
0 1 2 2 3
```粗心的解释可能会计算 0、1、2、3 处的阈值，并认为所有阈值都会产生有效的组。 但 0 的阈值将包括零分参与者，这是被禁止的，因此必须排除这种选择。 

另一个例子：```
3
0 5 5
```仅存在一个有效组：选择分数 5 包括两个 5，选择其他任何值要么违反规则，要么产生相同的集合。 

## 方法

 蛮力的想法是尝试每个可能的参与者子集并检查它是否满足规则。 对于每个子集，我们将验证两个条件：不包含零分参与者，如果包含参与者，则也包含所有得分较高或相同的参与者。 对于 n 个参与者，有 2^n 个子集，检查每个子集需要 O(n)，给出 O(n·2^n)，即使对于适度的 n，这也是不可行的。 

关键的观察结果是有效子集的结构极其严格。 一旦我们选择了得分为 x 的参与者，我们就被迫将得分至少为 x 的每个人都包括在内。 因此，我们不应该考虑指数子集，而应该考虑分数阈值。 

对分数进行排序后，每个有效组对应于选择一个不同的分数值作为截止值，但仅限于正分数。 每个不同的正分值精确定义了一个有效组：得分至少为该值的所有参与者。 如果我们将阈值从较高分数移至较低分数，我们只会添加更多参与者，而不会以创建超出不同分数级别的新配置的方式删除较早的参与者。 

因此，答案简化为计算存在多少个不同的正分值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n·2^n) | O(n·2^n) | O(n) | 太慢了|
 | 最佳 | O(n log n) | O(n log n) | O(1) 或 O(n) | 已接受 |

 ## 算法演练

 1. 将所有分数读入数组。 这是必要的，因为我们需要分析价值观的分布而不是个人身份。 
2. 删除或忽略所有零值。 这些参与者不能出现在任何有效的组中，因此他们不能影响哪些组存在。 
3. 对剩余的正分数进行排序。 排序将相等的值分组在一起，这样可以轻松识别不同的分数级别。 
4. 扫描排序列表并计算值更改的次数。 每个不同的值代表一个新的可能阈值。 
5. 输出此计数作为有效文凭作业集的数量。 

关键思想是，每个不同的正分数恰好定义了一个“切入点”，在该“切点”中所选集合会发生有意义的变化。 

### 为什么它有效

 排序后，所有参赛者按分数排列。 任何有效的选择必须对应于选择最低包含分数 x。 一旦x被固定，集合就被唯一地确定为所有得分≥x的元素。 因此，有效集合的数量正是可以作为最小值的不同值 x 的数量，这正是不同正分数的数量。 

同一值内的两个不同阈值不会产生不同的集合，并且零不能用作阈值，因为它违反了限制。 这使得有效集和不同正分数之间的映射是一对一的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a = [x for x in a if x > 0]
    a.sort()

    if not a:
        print(0)
        return

    cnt = 1
    for i in range(1, len(a)):
        if a[i] != a[i - 1]:
            cnt += 1

    print(cnt)

if __name__ == "__main__":
    solve()
```该实现首先过滤掉零，因为在任何有效选择中都明确不允许使用零。 排序用于将相等的分数分组在一起，以便可以在一次传递中对不同的值进行计数。 

计数器从 1 开始，因为正分数的非空列表始终贡献至少一个不同的值。 然后，只有当我们观察到不同值之间的转换时，我们才会增加计数器。 

一个常见的错误是在计算不同值之前忘记删除零，这会通过将零视为有效阈值来错误地夸大答案。

 ## 边缘情况

 一个关键的边缘情况是，除了约束保证至少一个非零之外，所有元素都为零，但我们仍然必须处理过滤删除所有内容的情况。 对于输入如：```
3
0 0 5
```过滤后我们得到`[5]`。 排序什么也不做。 该算法将计数初始化为 1 并返回 1，这对应于唯一有效的选择：得分为 5 及其以上的所有内容（仅是那些参与者）。 

另一种边缘情况是所有正值都相同时：```
4
0 7 7 7
```过滤后的列表是`[7, 7, 7]`。 循环从未发现值发生变化，因此 count 仍为 1。这正确地反映了仅存在一个阈值。 

最后，严格增加分数：```
4
1 2 3 4
```过滤和排序列表未更改。 每次转换都会增加计数，产生 4 个不同的有效集，符合每个分数级别定义不同截止值的想法。
