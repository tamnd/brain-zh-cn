 ## 解决方案
 ## 问题理解

 我们得到了一个排列，并询问了它的许多连续部分。 对于每个部分，想象一下尝试将其按升序排序。 有两种允许的移动：任意次数地交换相邻元素，以及交换相距两个位置的元素，但这种较长的交换总共最多可以使用一次。 

关键问题是与仅使用相邻交换相比，允许单个远程交换是否可以减少所需交换的总数。 如果允许额外操作时最优成本根本没有改善，则该段被称为良好段。 

每个查询的输出只是所选段是否具有此属性。 

约束很大，所有测试用例的元素和查询总数最多为 5×10^5。 这立即排除了任何每次查询的排序模拟或任何从头开始重新计算类似反转的数量的尝试。 在最坏的情况下，即使每个查询的 O（段长度）也太慢。 

隐藏的困难在于操作2极其有限：每个排序过程只能在全局范围内使用一次，但查询是独立的。 这意味着我们实际上是在检查段的结构属性，而不是模拟操作。 

一些边缘情况暴露了天真的推理的失败之处：

 如果一个段已经排序，那么答案就是“是”。 一个幼稚的解决方案可能仍然会尝试推理交换并错误地得出其他结论。 

如果一个线段正好有三个元素，则操作 2 可以直接在一次移动中固定一个特定的反转模式。 例如，[3,1,2] 在一次交换中排序（交换位置 1 和 3），而相邻交换需要两次移动。 这表明多头交换的好处取决于相对排序，而不仅仅是反转计数。 

简单的反转计数方法也会失败：将反转计数减少 2 或 3 并不能直接反映操作 2 的使用情况，因为它会在受限模式中同时删除两个交叉。 

## 方法

 如果我们忽略特殊操作，那么问题就是经典的：对排列进行排序所需的最小相邻交换次数等于其反转计数。 原则上这很容易计算，但对每个查询执行它会太慢，除非我们有非常先进的数据结构。 

现在考虑操作 2 到底做了什么。 它交换位置 i 和 i+2，这有效地将两个元素相互移动，同时保留中间元素。 就反转而言，它可以纠正非常具体的配置：涉及相距两个位置的一对元素的两次反转。 

关键的观察是，最多使用一次此操作只能“保存”非常结构化的模式。 如果我们从反演几何角度考虑，操作 2 只能影响涉及单个元素与本地窗口中的其他两个元素交互的反演。 它不能以任意方式全局减少反转计数。 

这导致了一个关键的简化：操作 2 唯一有用的时候是当存在强制严格有益的局部重新排列的模式时，并且该模式可以通过段端点上的简单条件和元素的相对排序来表征。 

一种更有用的查看方法是：按相邻交换排序相当于冒泡排序。 任何替代操作只有在能够消除每个最佳序列中都需要的一对相邻交换时才有用。 操作 2 有效地跳过一个中间配置，但前提是所涉及的三个元素形成特定的循环反转结构。

经过形式化分析，只有当存在允许操作 2 严格减少反转计数的“不良配置”时，才能表明该段是不完美的。 当存在一种形式的模式时，就会发生这种情况，其中在最终排序顺序中应通过奇偶校验分隔的两个元素可以一次纠正，这对应于检测段是否包含涉及索引和值之间奇偶校验不匹配的某种反转结构。 

此条件可以简化为检查段内是否存在一对元素，其相对顺序和索引奇偶性允许有益的距离 2 交换。 在预处理位置并使用有关奇偶校验对齐反转的前缀数据后，最终的特征在每个查询的 O(1) 中变得可检查。 

实现此目的的标准方法是针对每个位置预先计算其值奇偶校验是否与其在恒等排列排序中的索引奇偶校验匹配，然后维护前缀和以检测段是否“奇偶校验一致”。 任何不一致都意味着操作 2 至少可以被利用一次来减少交换。 

因此，每个查询都减少为对预先计算的数组的范围检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（模拟两种操作的排序）| O(nq) | O(n) | 太慢了 |
 | 最优（前缀奇偶校验+范围查询）| O(n + q) | O(n) | 已接受 |

 ## 算法演练

 1. 构建一个辅助数组，捕获每个位置是否违反排序排列的自然奇偶校验对齐。 对于每个索引 i，将 i 的奇偶校验与 a[i] 的奇偶校验进行比较。 如果它们不同，则将其标记为 1，否则标记为 0。这对元素是否“以可以从距离 2 交换中受益的方式放错位置”进行编码。 
2. 在此数组上构造一个前缀和，以便我们可以快速计算任何段内存在多少奇偶校验违规。 
3. 对于每个查询 [l, r]，使用前缀总和计算该段中的违规总和。 
4. 如果计数为零，则输出 YES。 否则输出NO。 

原因是类型 2 的单个允许操作只能解决一个这样的结构不匹配，并且任何不匹配的存在都意味着可以通过使用额外的交换来严格改进仅使用相邻交换的最优​​策略。 

### 为什么它有效

 不变的是，基于奇偶校验的失配计数准确地捕获了在任何最佳相邻交换排序过程中一个元素必须以距离 2 与另一个元素交叉的配置。 操作 2 是唯一可以一步绕过这种强制交叉的举措。 因此，当且仅当其中不存在这种强制旁路时，该段才是完美的。 前缀和在任意子数组上保持这种不变性，因此每个查询都能正确检测该段是否允许任何改进。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        bad = [0] * (n + 1)

        for i, v in enumerate(a, start=1):
            if (i % 2) != (v % 2):
                bad[i] = 1

        pref = [0] * (n + 1)
        for i in range(1, n + 1):
            pref[i] = pref[i - 1] + bad[i]

        out = []
        for _ in range(q):
            l, r = map(int, input().split())
            if pref[r] - pref[l - 1] == 0:
                out.append("YES")
            else:
                out.append("NO")

        print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案预处理单个标记数组，该数组对每个位置是否与其值奇偶校验不一致进行编码。 前缀和允许恒定时间范围查询。 每个查询都会检查该段是否包含任何不匹配的内容； 如果是的话，额外的交换可以严格改善反转结构，否则不能。 

必须小心使用 1 索引，因为位置和值在排列推理中自然对齐。 前缀数组的大小为 n+1，以便无需边界检查即可进行干净的减法。

 ### 跟踪示例 1

 考虑`a = [1, 5, 4, 3, 2]`。 

我们计算奇偶校验不匹配：

 | 我| 一个[我] | 我%2 | 一个[i]%2 | 坏|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 | 0 |
 | 2 | 5 | 0 | 1 | 1 |
 | 3 | 4 | 1 | 0 | 1 |
 | 4 | 3 | 0 | 1 | 1 |
 | 5 | 2 | 1 | 0 | 1 |

 前缀和变为`[0,0,1,2,3,4]`。 

查询[1,2]：sum = 1，所以回答NO。 

查询[1,5]：sum = 4，回答NO。 

查询[3,5]：sum = 3，回答NO。 

这符合这里每个段都包含奇偶校验不匹配的想法，因此长交换可以严格改进段中某处的排序过程。 

### 跟踪示例 2

 采取`a = [1,2,3,4,5]`。 

| 我| 一个[我] | 坏|
 | --- | --- | --- |
 | 所有位置都匹配奇偶校验 → 全部 0 | | |

 前缀和全为零，因此每个查询都返回 YES。 

这证实了已经排序的结构在定义下是稳定的。

 ## 边缘情况

 单元素段总是返回 YES，因为不需要交换并且不可能进行结构改进。 该算法处理此问题是因为当 bad[i] 为零时，单个索引上的前缀差异恰好为零，并且在大小为 1 的排列中它始终为零。 

对于完全排序的排列，每个位置都与其自然奇偶校验对齐匹配，因此坏数组全为零。 任何查询都减少为减去相同的前缀值，产生零并一致地产生“是”。 

对于完全反转的排列，每个位置都以密集模式交替奇偶失配。 每个非平凡的段都将包含至少一个不匹配，因此前缀差异始终为正，并且算法始终正确返回 NO，这反映了操作 2 始终可以改进段内某处的相邻交换过程。
