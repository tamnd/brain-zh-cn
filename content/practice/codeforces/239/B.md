 ## 解决方案
 ## 问题理解

 我们得到一个由数字组成的字符串，`<`， 和`>`人物。 每个查询都会选择一个子字符串，并将其视为小型磁带语言中的独立程序。 

解释器保留两个状态。 当前位置指向字符串的一个字符，当前方向为向左或向右。 最初，我们从最左边的字符开始，然后向右移动。 

数字的行为就像计数器。 当解释器访问一个数字时，它会打印当前值，然后将该数字减一。 如果该数字已经是`0`，它从程序中完全消失。 处理完该数字后，指针向当前方向移动一步。 

符号`<`和`>`只改变方向。 更新方向后，指针移动一步。 还有一个额外的规则：如果指针随后立即落在另一个方向符号上，则前一个方向符号就会消失。 

对于每个查询，我们必须计算每个数字出现的次数`0`到`9`在完整执行期间打印。 

限制非常小。 字符串长度和查询次数都最多`100`。 即使每个查询进行相当繁重的模拟也是可以接受的。 解决方案围绕`O(n^2)`甚至`O(n^3)`总操作量很容易符合限制。 

困难的部分不是性能，而是完全按照描述实现解释器。 有几个细节很容易处理不好。 

一个常见的错误是在打印之前更新数字。 考虑：```
1
```正确的行为是：```
print 1
digit becomes 0
print 0
digit disappears
```输出计数为：```
0 -> 1 time
1 -> 1 time
```如果我们先减少然后打印，我们会错误地错过`1`。 

另一个微妙的情况是删除方向符号。 假设程序是：```
><
```我们开始于`>`，方向变对了，我们继续前进`<`。 由于新字符也是方向符号，因此之前的字符`>`立即消失。 忘记这一删除会改变未来的指数并破坏模拟。 

删除后的索引变化是错误的另一个来源。 考虑：```
0<
```我们打印`0`，擦除它，剩下的程序就变成了`<`。 当前指针现在必须指向缩短数组中正确的下一个字符。 粗心的实现经常会在调整删除之前增加指针，并意外地跳过字符。 

## 方法

 最直接的解决办法就是从字面上模拟解释器。 

对于每个查询，我们提取子字符串并将其存储在可变结构（例如字符列表）中。 我们维持目前的立场和方向。 在每一步中，我们都会执行语句中的确切规则，如果字符消失则更新程序，并对打印的数字进行计数。 

这种暴力模拟已经足够快了。 数字在消失之前只能减少有限的次数。 方向符号也只能消失一次。 由于子串长度最多为`100`，每个查询的解释器步骤总数很小。 

粗略的上限很容易得出。 每个数字最多贡献`10`消失前打印。 每个方向符号最多消失一次。 即使在最坏的情况下，查询也只执行几千次操作。 

挑战在于突变下的正确性。 字符串长度动态变化，因此删除后必须仔细更新索引。 关键的观察是约束足够小，我们不需要任何复杂的优化。 忠实的模拟比尝试压缩状态或预计算转换更简单、更安全。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟 | O(q·n²) | O(q·n²) | O(n) | 已接受 |
 | 仔细的可变模拟| O(q·n²) | O(q·n²) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个查询，提取子字符串并将其转换为可变字符列表。 

我们需要可变性，因为数字和方向符号可能在执行过程中消失。 
2. 初始化当前位置`pos = 0`和方向`dir = 1`。 

我们使用`1`对于权利和`-1`为左。 
3. 重复同时`0 <= pos < len(program)`。 

一旦指针离开当前程序边界，执行就会停止。 
4. 如果当前字符是数字：

 增加该数字的答案计数器。 

如果数字是`0`，从列表中删除该字符。 否则减一。 

然后向当前方向移动一步。 

删除必须在打印之后进行，因为解释器首先打印当前值。 
5. 如果当前字符是`<`或者`>`:

 相应地更新方向。 

存储当前索引，因为该符号可能会消失。 

朝着新的方向迈出一步。 
6. 从方向符号移动后，检查新位置是否仍在程序内，以及新字符是否也在程序内。`<`或者`>`。 

如果两个条件都成立，则擦除之前的方向符号。 
7. 删除当前指针之前的字符时，将指针索引减一。 

这补偿了删除后数组中的左移。 
8. 继续，直到指针退出程序。 

### 为什么它有效

 模拟保持与解释器定义完全相同的状态：当前可变程序、当前指针位置和移动方向。 

每个解释器规则的应用顺序与语句相同。 数字在修改之前打印，方向改变在移动之前发生，方向符号仅在到达另一个方向符号后才被删除。 

唯一棘手的部分是删除后的索引维护。 每当当前指针之前的字符消失时，所有后面的索引都会左移一位。 调整指针保留了以下不变式：`pos`总是指解释器接下来应该访问的相同逻辑字符。 

由于每次循环迭代精确地反映一个解释器步骤，因此生成的数字计数是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def simulate(sub):
    s = list(sub)
    ans = [0] * 10

    pos = 0
    direction = 1

    while 0 <= pos < len(s):
        cur = s[pos]

        if cur.isdigit():
            d = int(cur)
            ans[d] += 1

            if d == 0:
                s.pop(pos)

                if direction == -1:
                    pos -= 1
            else:
                s[pos] = str(d - 1)
                pos += direction

        else:
            direction = -1 if cur == '<' else 1

            old_pos = pos
            pos += direction

            if 0 <= pos < len(s) and s[pos] in '<>':
                s.pop(old_pos)

                if old_pos < pos:
                    pos -= 1

    return ans

def solve():
    n, q = map(int, input().split())
    s = input().strip()

    out = []

    for _ in range(q):
        l, r = map(int, input().split())

        res = simulate(s[l - 1:r])
        out.append(' '.join(map(str, res)))

    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```该解决方案直接遵循解释器规则。 

每个查询的子字符串都会变成一个列表，因为 Python 字符串是不可变的。 删除频繁发生，因此列表操作使实现更加简洁。 

一旦指针离开当前有效范围，主循环就会终止。 由于程序会动态收缩，因此我们总是与当前长度进行比较。 

数字处理有两个独立的分支。 对于数字`1`通过`9`，我们减少原地角色并正常移动。 为了`0`，我们完全删除该角色。 删除后指针的更新是微妙的。 如果我们向左移动，数组会在当前逻辑下一个位置之前收缩，因此我们递减`pos`再次。 

方向符号需要再次仔细调整。 我们首先根据更新的方向移动，然后检查目的地是否是另一个方向符号。 如果是这样，我们就删除前一个。 当删除的索引位于当前位置之前时，当前位置左移一位，因此我们补偿为`pos -= 1`。 

这些索引更正是正确模拟与删除后默默跳过字符的解决方案之间的区别。

 ## 边缘情况

 考虑该程序：```
0
```从数字开始执行`0`。 解释器打印`0`，然后删除该字符，因为它无法进一步减少。 指针现在指向空程序外部，因此执行停止。 

该算法可以正确处理这个问题，因为`d == 0`分支在计算打印数后立即删除该字符。 

现在考虑：```
><
```指针开始于`>`，改变方向向右，并移动到`<`。 由于目的地也是一个方向符号，所以前面的`>`消失。 指针现在位于`<`，它将它发送到左侧并立即发送到程序之外。 

该实现使用以下命令重现了此行为`old_pos`并仅在移动后删除前一个符号。 

最后，考虑：```
1<
```指针打印`1`，将数字更改为`0`，然后向右移动到`<`。 这`<`向左改变方向，移回到`0`。 这`0`打印并删除，之后指针向左退出。 

这里重要的细节是删除后左移时的索引调整。 没有`pos -= 1`在删除分支中，当数组收缩后，模拟将从错误的位置继续。
