 ## 解决方案
 ## 问题理解

 我们有一个包含 (n) 个元素的集合 (S)，并且 (S) 的每个子集必须涂成红色或蓝色。 对于子集 (T)，将其涂成红色的成本 (R_T)，将其涂成蓝色的成本 (B_T)。 成本可能是负的，因此目标不仅仅是独立选择更便宜的颜色。 

着色有一个结构限制。 每当两个子集 (A) 和 (B) 具有相同的颜色时，它们的并集 (A\cup B) 也必须具有相同的颜色。 换句话说，每种颜色的子集必须在并集下封闭。 

输入通过位掩码表示子集。 Mask (i) 表示恰好包含那些相应位被设置的元素的子集。 因此，这两个数组各自包含 (2^n) 个成本。 我们需要所有 (2^n) 个子集上所选绘画成本的最小可能总和。 

边界 (n\le20) 是主要信号。 最多有 (2^{20}=1,048,576) 个子集，因此 (O(2^n)) 或 (O(n2^n)) 解决方案是现实的。 在两秒限制下，任何诸如 (O(3^n)) 之类的东西在 (n=20) 时都已经太大了，因为 (3^{20}=3,486,784,401)。 (256) MiB 的内存限制也意味着我们应该只保留几个大小为 (2^n) 的数组，而不是存储由多个子集索引的大型 DP 表。 官方的约束和限制是 (n\le20)、成本在 (-10^9) 和 (10^9) 之间、两秒和 (256) MiB。 

有几种边缘情况很容易被错误处理。 首先，(n=0) 只留下空子集。 例如，```
0
-129363358
227605714
```有答案`-129363358`，因为只有一个子集，我们只需选择其更便宜的颜色。 该示例包含在原始声明中。 

负成本是错误的另一个来源。 假设成本为非负的解决方案可能会尝试将问题解释为正常的最小成本着色，但负成本可以使看似昂贵的颜色在全局上变得更可取，因为并集限制耦合了许多子集。 

最后，空子集必须被视为普通子集。 对于（n=1），恰好有两个子集，空集和单例。 空集没有特殊的着色规则豁免。 忘记将其成本包含在基本情况中会产生恰好偏离一个子集成本的答案。 

## 方法

 思考该问题的直接方法是确定每个子集的有效着色。 这意味着考虑 (2^{2^n}) 种可能的着色并检查并集条件。 这对于非常小的（n）来说已经是无望的了，所以我们需要利用联合闭包的特殊结构。 

更有用的强力动态规划方法着眼于固定集（S）。 假设 (S) 是红色。 在 (S) 的所有蓝色子集中，取它们的并集并将其称为 (V)。 因为蓝色子集在并集下是封闭的，所以 (V) 本身是蓝色的，并且是唯一的最大蓝色子集。 (V) 中未包含的每个子集都必须是红色的，因为否则它将是另一个蓝色子集，其与 (V) 的并集将大于 (V)。 

这给出了一个枚举 (V\subseteq S) 的 DP。 对于每个（S），我们可以尝试所有可能的（V），解决（V）内部的着色问题，并为（V）外部的所有子集支付红色。 对每对 (V\subseteq S) 执行此操作需要 (O(3^n)) 时间。 在 (n=20) 时，大约有 (34.9) 亿个子集关系，远远超出了限制。 如果 (S) 是蓝色，则同样的推理适用。 这个结构性DP是正确的，但它检验了太多的可能性。 (O(3^n)) 观点也是发现更快递归的有用方法。 

关键的观察是我们实际上不需要识别最大的相反颜色子集。 假设 (S) 是红色。 必须存在某个元素 (e\in S)，使得满足 (e\in T\subseteq S) 的每个子集 (T) 都是红色。 要了解原因，请假设相反的情况。 那么对于每个元素 (e)，都有一些包含 (e) 的蓝色子集。 将所有这些蓝色子集并集得到 (S)。 由于蓝色子集是并闭的，因此 (S) 本身必须是蓝色，这与 (S) 是红色相矛盾。 

一旦选择了这样的元素 (e)，所有包含 (e) 的子集的颜色就会强制为红色。 其余子集正是 (S\setminus{e}) 的子集，并且它们可以作为独立的较小实例进行最佳着色。 这将结构观察变成了面具上的重现。 

令(R(S))表示(S)的每个子集的红色成本之和，并类似地定义(B(S))。 如果我们从 (S) 中删除 (e)，则 (R(S)-R(S\setminus{e})) 正是包含 (e) 的 (S) 的所有子集的总红色成本。 蓝色也是如此。 

如果 (dp[S]) 表示对 (S) 的所有子集进行着色的最小成本，而不固定 (S) 的颜色，则

 \min_{e\in S}
 \左(
 dp[S\setminus{e}]
 +
 \分钟\左(
 R(S)-R(S\setminus{e}),
 B(S)-B(S\setminus{e})
 \右）
 \右）。 
]

 第一项递归地为所有不包含 (e) 的子集着色。 第二项选择包含 (e) 的所有子集是红色还是全部是蓝色。 

我们只需要计算 (R(S)) 和 (B(S))，这是 (O(n2^n)) 中的标准子集和，或 SOS DP。 最终递归也将每个集合元素考虑一次，因此总数仍然是 (O(n2^n))。 这是公认的解决方案所使用的最佳方法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对有效结构选择的蛮力 | (O(3^n)) | (O(2^n)) | 太慢了|
 | 最佳 SOS DP + 面罩 DP | (O(n2^n)) | (O(2^n)) | 已接受 |

 ## 算法演练

1. 读取两个成本数组。 Mask(s)表示原始集合的子集，因此有(2^n)个掩码。 
2. 将红色数组转换为 (R[s])，即 (s) 的每个子掩码上的红色成本之和。 对蓝色数组进行同样的变换，得到(B[s])。 这是标准的 SOS DP，完成后，(t=s\setminus{e}) 的差值 (R[s]-R[t]) 正是包含 (e) 的 (s) 子集的总红色成本。 
3. 设置 (dp[0]=\min(R[0],B[0]))。 空集没有要删除的元素，因此它是基本情况。 由于它是 (n=0) 时唯一的子集，因此这也立即处理最小可能的实例。 
4. 按递增的数字顺序处理每个非空掩码。 对于 (s) 的每个设置位 (e)，设 (t=s\setminus{e})。 因为(t<s)，它的DP值已经计算出来了。 
5. 假设所选元素为(e)。 包含 (e) 的 (s) 的每个子集必须接收一种公共颜色。 如果该颜色是红色，则它们的总贡献为 (R[s]-R[t])。 如果是蓝色，则它们的贡献为 (B[s]-B[t])。 这两个值中较小的一个是该特定 (e) 的最佳选择。 
6. 更新

 \分钟\左(
 dp[s],
 dp[t]+\min(R[s]-R[t],B[s]-B[t])
 \右）。 
]

 1.所有掩码都处理完后，输出(dp[2^n-1])，因为这个掩码代表完整的集合(S)，所以原集合的所有子集都已经被考虑了。 

### 为什么它有效

 不变量是 (dp[S]) 是 (S) 的每个子集的有效着色的最小成本。 考虑非空 (S) 的任何最佳着色，并假设 (S) 是红色。 联合闭包条件保证某个元素 (e\in S) 具有包含 (e) 的每个子集都是红色的属性。 删除 (e) 恰好留下 (S\setminus{e}) 的子集，其最优成本为 (dp[S\setminus{e}])。 所有包含 (e) 的剩余子集都被迫变为红色并贡献 (R[S]-R[S\setminus{e}])。 当 (S) 为蓝色时，同样的论点也适用。 因此，每个最佳着色都由我们的一个过渡表示，而每个过渡都会产生有效的着色。 取最小值正好给出(dp[S])。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve(data=None):
    if data is None:
        n = int(input())
        m = 1 << n
        red = list(map(int, input().split()))
        blue = list(map(int, input().split()))
    else:
        it = iter(map(int, data.split()))
        n = next(it)
        m = 1 << n
        red = [next(it) for _ in range(m)]
        blue = [next(it) for _ in range(m)]

    # SOS DP:
    # red[s] = sum(red[t]) for all t subset of s.
    # blue[s] = sum(blue[t]) for all t subset of s.
    step = 1
    while step < m:
        block = step << 1
        for base in range(0, m, block):
            end = base + step
            for s in range(base, end):
                red[s + step] += red[s]
                blue[s + step] += blue[s]
        step <<= 1

    INF = 10**30
    dp = [INF] * m
    dp[0] = min(red[0], blue[0])

    for s in range(1, m):
        best = INF
        x = s
        while x:
            bit = x & -x
            t = s ^ bit

            add = red[s] - red[t]
            other = blue[s] - blue[t]
            if other < add:
                add = other

            cand = dp[t] + add
            if cand < best:
                best = cand

            x ^= bit

        dp[s] = best

    return str(dp[m - 1])

if __name__ == "__main__":
    print(solve())
```第一部分存储两个原始成本数组。 然后，SOS 变换将其含义从“恰好是该子集的成本”更改为“所有子掩码的总成本”。 就地变换是安全的，因为每个位都会处理一次，并且当将一位添加到掩码时，没有该位的值已经在当前阶段最终确定。 

基本情况使用`min(red[0], blue[0])`，因为 SOS 变换后`red[0]`和`blue[0]`仍然代表单独的空子集的成本。 

对于每个面膜，`x & -x`提取一组位。 删除该位给出`t = s ^ bit`。 迭代设置的位而不是所有 (n) 个位置可以避免不必要的检查并精确访问 (\operatorname{popcount}(s)) 个转换。 

表达式`red[s] - red[t]`是这些子掩码的红色成本之和`s`包含被删除的元素。 相应的蓝色表达式具有相同的解释。 由于 Python 整数具有任意精度，因此可能的总成本大约可以达到 (2^{20}\cdot10^9)，不需要特殊的溢出处理。 

掩码的数字顺序对于 DP 排序也足够了。 删除设置位总是会产生较小的掩码，因此`dp[t]`之前可用`dp[s]`被评估。

 ## 边缘情况

 对于（n=0），掩码空间仅包含掩码`0`。 SOS变换无关，DP​​初始化`dp[0]`两种成本中较便宜的一个。 对于具体输入```
0
-129363358
227605714
```该算法计算`dp[0] = min(-129363358, 227605714)`, 给予`-129363358`。 这正是单个空子集所需的行为。 

对于负成本，请考虑```
1
-5 -10
0 -1
```红色的空子集最便宜，为`-5`，并且单例也是红色最便宜的，在`-10`，所以答案是`-15`。 DP 开头为`dp[0] = -5`。 面膜用`1`，去掉它唯一的一点叶子掩码`0`; 红色增量为`-10`，而蓝色增量是`-1`。 最小增量为`-10`，生产`dp[1] = -15`。 循环中的任何地方都没有出现关于成本正性的假设。 

对于所有相同的成本，请考虑```
2
5 5 5 5
7 7 7 7
```四个子集中的每一个子集的成本`5`红色和`7`蓝色。 将每个子集着色为红色是有效的，因为红色族是整个幂集并且通常是并闭的。 答案是`4*5 = 20`。 递归找到相同的结果，因为每次转换都选择红色增量`5`每个新强制子集而不是蓝色增量`7`。 

最大尺寸边界为 (n=20)，其中 mask`2^20-1 = 1,048,575`是最大的有效索引。 一个常见的实现错误是意外分配`2^n-1`条目或使用访问索引的包含循环`2^n`。 该解决方案准确分配`1 << n`条目和处理掩码来自`1`通过`m-1`，因此最大掩码仅处理一次，而不会出现越界访问。 

主要逻辑边缘情况是其最佳着色包含两种颜色的集合。 递归并不假设整个集合是单色的。 相反，它仅依赖于一个元素的存在，该元素包含子集晶格的一半，其颜色与整个集合的颜色相同。 一旦该元素被修复，剩下的一半就会被递归优化。 这正是使并闭条件变得有用而无需枚举完整着色的原因。
