 ## 解决方案
 ## 问题理解

 磁盘是固定大小单元的线性阵列，每个单元要么存储某个文件的片段，要么为空。 每个文件都已存在于磁盘上，但其碎片可能分散在任意位置，同时仍以该文件的正确内部顺序出现。 

允许的操作是破坏性复制：选择源单元格并将其值复制到目标单元格中​​，覆盖其中的任何内容。 这意味着对目标单元的任何重用都会永久破坏其先前的内容。 在覆盖任何数据之前，我们必须仔细管理仍然需要哪些数据。 

目标是重新排列数据，使每个文件成为一个连续的单元块，并且所有文件从磁盘开头以任何顺序连续打包。 放置所有文件后，所有剩余未使用的单元格必须在最后分组。 

关键的约束是我们不需要最小化操作，但我们必须保持在线性范围内，特别是最多两倍的单元格数量。 

重要的结构观察是每个单元最多属于一个文件，因此不存在所有权重叠。 这意味着我们有效地将不相交的标记片段重新排列成连续的间隔。 

一种简单的方法是反复选择一个文件，收集其碎片，然后通过搜索和复制将它们“冒泡”到位。 这很快就会变得二次或更糟，因为每个放置都可能需要扫描整个磁盘来定位源。 

当我们过早覆盖有用的源单元时，就会出现天真的贪婪压缩的微妙失败情况。 例如，如果我们在确保保留或重新定位 A 的所有其他片段之前将文件 A 的一个片段移动到其最终位置，则可能会破坏某些所需数据的唯一副本。 由于复制具有破坏性，因此操作顺序比最终布局更重要。 

约束 n, m ≤ 200 表明 O(n^2) 构造是可以接受的，但我们还必须确保干净的不变驱动构造以避免意外数据丢失。 

## 方法

 暴力破解的想法是重复扫描磁盘以查找下一个错位的片段并将其移向目标区域。 每次移动都需要找到正确的来源和免费或一次性的目的地。 由于最多 n 个单元中的每个单元都可能在 O(n) 次扫描中移动，因此这会导致简单实现中的 O(n^3) 行为，并且在给定结构的情况下是不必要的。 

关键的见解是，我们实际上从来不需要全局地“解决文件之间的相互依赖关系”。 相反，我们可以通过保留最终位置并使用任何可用的正确源单元格填充它们来逐步构建最终布局。 因为每个文件的片段都是独立的，所以我们可以将其所有出现视为可互换源池，只要我们在最后一次使用之前保留至少一个有效副本即可。 

我们首先计算每个文件的所有连接组件，然后模拟打包过程：以任意顺序将最终的连续段分配给文件，对于每个目标单元格，从该文件的任何当前可用的源单元格进行复制，该源单元格尚未处于其最终正确的位置。 当不存在这样的“额外”源时，我们依赖这样一个事实：至少有一个事件必须仍然保持在其最终位置之外，直到最后一步，以确保我们永远不会过早丢失所有副本。 

主要的技术技巧是，我们将磁盘视为具有一组“空闲或安全缓冲区”，当我们覆盖不再用作源的位置时，这些缓冲区会累积。 这些缓冲区使我们始终能够找到中间移动的目的地，而不会破坏未来的要求。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) | O(n^3) | O(n) | 太慢了 |
 | 最佳 | O(n^2) | O(n^2) | O(n) | 已接受 |

## 算法演练

 我们从左到右构造最终布局，以任意顺序将连续的段分配给文件。 

1. 为每个文件计算其当前位置的列表。 这些位置是该文件数据的唯一有效来源。 
2. 在磁盘上维护一组未使用的位置。 这些是可以临时存储复制数据的潜在缓冲单元。 
3. 选择任意文件顺序。 为每个文件分配一个长度等于其大小的最后一个段，紧邻前一个文件的段之后放置。 
4. 对于每个文件，从左到右处理其分配的段。 对于每个目标位置，如果该位置已包含同一文件的正确片段，则跳过它。 否则，我们必须将正确的片段放入这个位置。 
5. 要填充目标位置，请选择包含尚未固定在最终正确位置的正确文件的任何当前位置（如果可能）。 如果所有剩余的源都已经正确，我们就处于该文件的最后一步，因此可以使用任何剩余的源。 
6. 执行从所选源到目标的复制操作，并更新状态：目标现在成为该文件将来操作的有效源，而源在逻辑上保持可用，但如果它与其最终位置匹配，则可能被视为“已用”。 
7. 继续，直到所有文件都放入其指定的连续块中。 

关键的不变量是，对于每个文件（可能除了当前正在最终确定的文件之外），都至少存在一个可用的未最终确定的副本。 这保证了当我们覆盖一个位置时，我们永远不会过早地消除最后一个可用的源。 

正确性取决于这样一个事实：我们仅以受控顺序将文件的单元格提交到其最终位置，确保没有文件在完成之前丢失所有可用的代表。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    pos = [[] for _ in range(m)]
    disk = [0] * (n + 1)

    for i in range(m):
        tmp = list(map(int, input().split()))
        k = tmp[0]
        for x in tmp[1:]:
            pos[i].append(x)
            disk[x] = i

    # assign final segments
    start = 1
    seg = []
    for i in range(m):
        seg.append((start, start + len(pos[i]) - 1))
        start += len(pos[i])

    ops = []

    # build target array conceptually
    target_file = [0] * (n + 1)
    for i in range(m):
        l, r = seg[i]
        idx = 0
        for p in range(l, r + 1):
            target_file[p] = i

    # current ownership tracking
    cur_pos = [set(lst) for lst in pos]

    def find_source(f):
        # pick any current source
        for x in cur_pos[f]:
            return x
        return -1

    for f in range(m):
        l, r = seg[f]
        for p in range(l, r + 1):
            if disk[p] == f:
                continue
            src = find_source(f)
            ops.append((src, p))
            old = disk[p]
            disk[p] = f
            cur_pos[f].add(p)

    print(len(ops))
    for a, b in ops:
        print(a, b)

if __name__ == "__main__":
    solve()
```该实现保留当前占用每个单元格的文件的直接表示。 对于每个文件，我们维护一组已知位置，作为有效源池。 填充文件的最后一段时，我们从该文件的任何可用源复制到下一个所需位置。 

关键的微妙之处在于我们在复制后立即更新目标单元格的所有权，因此它成为一个额外的有效源。 这可以防止资源耗尽，并确保将来的副本始终有可用的东西。 

我们从不显式地对空闲单元进行建模，因为覆盖的位置自然会成为当前正在处理的文件的可用池的一部分。

 ## 边缘情况

 当文件内部已经连续但位于错误的全局区域时，就会出现关键的边缘情况。 该算法仍然为其分配一个最终段，并且仅在必要时才在该段内进行复制； 由于所有目标都已匹配，因此不会发生任何操作。 

另一种边缘情况是文件只有一个片段。 在这种情况下，它的唯一来源也是它的最终目的地。 该算法正确地不执行自复制，因为它会跳过匹配位置。 

第三种情况是文件完全分散并与其他文件交错。 每个目的地立即成为源池的一部分的不变性确保我们永远不会在构建过程中用完可用的片段。
