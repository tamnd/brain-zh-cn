 ## 解决方案
 ## 问题理解

 我们得到一个由大写和小写字母组成的字符串。 Patrick 想要将其转换为“奇特”字符串，定义为左侧全部大写字母，右侧全部小写字母。 我们可以通过一次操作来更改任何字母的大小写。 我们的目标是计算实现奇特格式所需的此类操作的最少数量。 

输入字符串最长可达 100,000 个字符。 这立即排除了检查每个可能的分区并在线性时间内从头开始计算每个分区的更改数量的解决方案，因为这将是 O(n²) 并且太慢。 我们需要一个最多扫描字符串恒定次数的解决方案，最好是 O(n)。 该字符串保证非空，因此我们不需要处理空输入情况，但我们确实需要处理已经全部大写、全部小写或交替字母的字符串。 

当字符串已经很奇特时，就会出现不明显的边缘情况。 例如，输入`ABCdef`需要 0 次更改，而总是计算双方的天真的方法可能会错误地输出正数。 另一个棘手的场景是`aAaA`，其中大写和小写字母完全交错。 该算法必须正确计算最佳分割点（可能位于字符串的中间），并更改字母以匹配该分割点。 

## 方法

 暴力方法会迭代字符串的每个可能的分割（从 0 到 n），将左侧全部视为大写，将右侧全部视为小写。 对于每个分割，我们计算左段中小写字母的数量和右段中大写字母的数量。 对这些进行求和就得出了该拆分所需的操作数。 然后我们取所有分割中的最小值。 虽然这在概念上很简单，但在最坏的情况下成本为 O(n²)，因为对于 n 个分割中的每一个，计算两侧的字母需要 O(n)。 对于 n 达到 100,000 的情况来说，这太慢了。 

优化的关键在于可以将问题简化为前缀/后缀计数策略。 我们可以为每个索引预先计算到该位置的累积小写字母数量以及从该位置到末尾的累积大写字母数量。 然后，对于任何分割点，我们可以使用这些累积计数来计算 O(1) 中所需的更改数量。 这将总复杂度降低到 O(n) 时间和 O(n) 空间。 从概念上讲，我们从左到右扫描一次以构建前缀计数，从右到左扫描一次以构建后缀计数，然后评估单个线性通道中的所有分割点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 前缀/后缀计数 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算前缀数组`lower_prefix`在哪里`lower_prefix[i]`计算小写字母的数量`s[0..i-1]`。 这表示如果我们在之后进行拆分，则将左段转换为全部大写所需的更改数量`i-1`。 
2. 计算后缀数组`upper_suffix`在哪里`upper_suffix[i]`计算大写字母的数量`s[i..n-1]`。 这表示如果我们之前进行拆分，则将右侧段转换为全部小写所需的更改数量`i`。 
3. 初始化变量`min_actions`有大量。 迭代所有分割点`i`从 0 到 n。 对于每个分割，所需的操作数为`lower_prefix[i] + upper_suffix[i]`。 更新`min_actions`到所有分裂的最小值。 
4. 输出`min_actions`。 

工作原理：在每个分割点，前缀数组准确地告诉我们左侧需要将多少个小写字母转换为大写字母，而后缀数组则告诉我们右侧需要将多少个大写字母转换为小写字母。 评估所有分割可确保我们找到全局最佳点，因为任何花哨的字符串都可以表示为大写和小写字母之间的某种分割。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

lower_prefix = [0] * (n + 1)
for i in range(n):
    lower_prefix[i + 1] = lower_prefix[i] + (1 if s[i].islower() else 0)

upper_suffix = [0] * (n + 1)
for i in range(n - 1, -1, -1):
    upper_suffix[i] = upper_suffix[i + 1] + (1 if s[i].isupper() else 0)

min_actions = n  # maximum possible actions is n
for i in range(n + 1):
    actions = lower_prefix[i] + upper_suffix[i]
    if actions < min_actions:
        min_actions = actions

print(min_actions)
```前缀和后缀数组存储累积计数，以避免重复扫描字符串。 计算的循环`min_actions`评估所有可能的分割点，包括第一个字符之前和最后一个字符之后，这可以正确处理已经全部大写或全部小写的字符串。
