 ## 解决方案
 ## 问题理解

 鉴于市政府的干预，我们被要求确定反对派最早可以举行示威的广场。 有`n`广场按照距离市中心的距离逐渐增加排列，其中 1 号广场是最中心的。 每个方格`i`有成本`a[i]`以便行政部门占领它。 政府有总预算`b`。 反对派有`k`提交示威请求的天数，政府每天都可以通过封锁反对派申请的广场来做出回应，如果政府负担得起的话，将他们转移到目前最糟糕的自由广场。 目标是确定如果双方都采取最佳行动，对手可以确保的最小数量的方格。 

该问题的约束条件为`n = 10^5`和`b`最多`10^18`。 这排除了任何复杂度低于 O(n log n) 的算法，因为 O(n^2) 约为 10^10 次操作，并且对于 2 秒的限制来说太慢了。 每个`a[i]`可以大到 10^9，因此成本计算必须使用 64 位整数进行处理。 

棘手的边缘情况涉及非常小的`k`或很小`b`。 例如，如果`b`为零，则政府不能封锁任何方格，反对派应始终占据方格 1。反之，如果`b`如果面积非常大，政府可以迫使反对派到最后一个可用的方格。 另一个微妙的情况发生在天数`k`相对于`n`; 反对派可以尝试多种应用程序，迫使政府在多个广场上花钱，最终限制政府可以封锁的广场。 

## 方法

 暴力方法将模拟每天的应用程序。 每一天，我们都会尝试反对派可以申请的每一个方格，让政府做出最佳回应，并跟踪哪些方格被采用。 该模拟需要嵌套迭代`k`天和`n`正方形，可能`O(k*n)`每天的操作次数。 对于最坏情况的值`n = 10^5`和`k = 10^5`，这种方法行不通。 原则上是正确的，但速度太慢。 

关键的见解来自于认识到反对派的最佳策略是选择一个一旦政府预算耗尽后他们能够负担得起的广场。 管理行为是确定性的：它们总是针对免费方块中当前最昂贵的方块。 因此，我们只需要检查`k+1`最早的方阵，因为反对派有`k`迫使政府花钱的日子。 政府将封锁`k`最昂贵的广场之一`k+1`正方形，留下这些中的最小值`k+1`作为反对派可以保证的最早的方阵。 这将问题简化为寻找最小值`a[i]`其中第一`k+1`平方并计算政府的支出，产生线性 O(n) 解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(k*n) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取方格数`n`, 天数`k`, 政府预算`b`，以及费用清单`a`。 
2. 只考虑第一个`k+1`正方形。 对手可以轮流尝试这些方格中的每一个`k`如果政府试图阻止他们的话，就会迫使他们花钱。 
3. 计算第一个中的最小值`k+1`正方形，因为在政府支出之后`k`该部分中最昂贵的方格，剩余的方格将是反对派最早能够负担得起的方格。 
4. 确定该最小成本平方的从 1 开始的索引。 该指数是对手的最佳平方。 
5. 打印结果。 

为什么有效：反对派可以随时提交申请`k`第一个最昂贵的方块`k+1`。 政府可以阻止`k`方格，每日一格。 剩下的方格将是政府无法封锁的编号最小的方格，以确保反对派尽可能早地占领方格。 由于政府总是在最昂贵的方格上花费，因此我们跟踪第一个方格中的最小值的不变式`k+1`平方保证正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
b = int(input())
a = list(map(int, input().split()))

# consider first k+1 squares
min_cost = a[0]
min_index = 0
for i in range(1, k+1):
    if a[i] < min_cost:
        min_cost = a[i]
        min_index = i

# output is 1-based index
print(min_index + 1)
```该解决方案有效地读取输入，仅迭代第一个`k+1`平方，并跟踪最小成本及其相应的指数。 使用基于 0 的索引进行迭代并转换为基于 1 的输出可防止差一错误。 我们不直接模拟行政预算，因为洞察表明，第一个预算中的最小值`k+1`自动考虑政府的支出能力`k`天。
