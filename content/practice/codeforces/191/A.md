 **求解时间：** 1m 42s

 ## 解决方案
 ## 问题理解

 我们得到了按时间顺序排列的国王姓名缩写列表。 每个名称都是小写字符串。 我们可以选择其中一些名字来组成一个王朝，同时保留它们原来的秩序。 

一个有效的王朝必须满足两个条件。 

每个所选名称的最后一个字符必须等于下一个所选名称的第一个字符。 这创建了一条链。 

王朝还必须形成一个整体循环，这意味着第一个选择的名称的第一个字符必须等于最终选择的名称的最后一个字符。 

王朝名称本身是所有选定字符串的串联，因此目标是最大化所有选定名称的总长度。 

关键的观察结果是，只有字符串的第一个和最后一个字母与兼容性有关。 内部字符永远不会影响转换。 名字的贡献就是它的长度。 

这些约束完全塑造了解决方案。 我们最多可能有$5 \cdot 10^5$弦，所以任何二次方都是不可能的。 即使存储所有对之间的转换也已经太大了。 由于每个字符串长度最多为 10，因此单独处理每个名称的成本较低，但我们必须保持每个名称的工作接近恒定时间。 

由于只有 26 个小写字母，因此字母表上的动态规划解决方案变得可行。 任何使用基于开始和结束字母的状态的算法最多有$26^2 = 676$州，很小。 

有几种边缘情况可能会默默地破坏不正确的解决方案。 

考虑第一个和最后一个字符已经匹配的单个字符串。```
1
abca
```正确答案是 4。粗心的实现如果只查找不同字符串之间的转换，就会错误地返回 0。 

当需要跳过字符串时，会出现另一种微妙的情况。```
3
abc
ca
cba
```最佳王朝使用第一个和第三个字符串，产生长度 6。总是立即扩展下一个兼容字符串的贪婪方法将停止于`"abc" + "ca"`并错过更好的解决方案。 

第三个陷阱是更新期间错误地覆盖 DP 状态。```
3
ab
bc
ca
```答案是 6。如果不小心就地执行更新，则当前字符串可能会在同一迭代中多次重复使用，从而有效地允许不可能的链。 

最后，可能根本没有有效的循环。```
2
ab
bc
```没有选定的子序列形成循环，因此答案为 0。返回最佳链而不是最佳循环将是错误的。 

## 方法

 蛮力的想法很简单。 我们尝试字符串的每个子序列，检查相邻字符串是否正确连接，并验证整个序列是否形成循环。 

这是有效的，因为规则仅依赖于相邻的字符串以及整体的第一个和最后一个字母。 问题是子序列的数量。 和$n$字符串，有$2^n$可能的选择。 即使是为了$n = 50$，这已经是无望了，真正的极限是$5 \cdot 10^5$。 

更合理的暴力变体在子集或图形路径上使用动态编程，但这仍然会崩溃，因为输入大小巨大。 

问题的结构提供了更强有力的观察。 每个字符串仅提供三个有意义的信息：

 第一个信。 

最后一封信。 

长度。 

字母表仅包含 26 个字母，因此可能的起始结束对的数量很少。 我们不需要记住确切的序列，而只需要记住每对可能的起始和结束字母的最佳总长度。 

定义：$dp[i][j]$=第一个字符串以字母开头的有效链的最大总长度$i$并且当前的最后一个字符串以字母结尾$j$。 

当处理来自的新字符串时$a$到$b$与长度$w$，我们可以：

 启动一个仅包含该字符串的新链。 

扩展每个现有的链，结尾为$a$。 

这是可能的，因为兼容性仅取决于匹配的边界字母。 链的完整历史并不重要。 

由于只有 26 个可能的结尾字母，因此每个字符串仅执行大约 26 次转换。 总工作量大致为$26 \cdot n$，很容易符合限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n)$|$O(n)$| 太慢了 |
 | 最佳DP |$O(26 \cdot n)$|$O(26^2)$| 已接受 |

 ## 算法演练

 1. 创建一个 26 × 26 DP 表，初始化为负无穷大。 

国家$dp[i][j]$存储以字母开头的链的最大总长度$i$目前以字母结尾$j$。 
2. 按照输入的顺序对字符串进行一一处理。 

保留顺序是强制性的，因为国王按时间顺序出现。 
3. 对于当前字符串，提取：

 - 它的起始角色$a$- 它的结尾字符$b$- 它的长度$w$4. Start a new chain using only this string.

 更新：$$dp[a][b] = \max(dp[a][b], w)$$这处理的是只有一个国王的王朝。 

1. 尝试扩展当前以以下结尾的每条链$a$。 

对于每个可能的起始字母$s$:$$dp[s][b] = \max(dp[s][b], dp[s][a] + w)$$这是有效的，因为当前字符串可以合法地跟随任何最后一个字母等于第一个字母的链。 

1. 注意不要在同一次迭代中多次重复使用当前字符串。 

为了避免这种情况，请在更新之前复制旧值，或使用相关列的快照进行迭代。 
2.所有字符串处理完毕后，答案为：$$\max(dp[c][c])$$总共 26 个字母$c$。 

仅当第一个和最后一个字母全部匹配时，王朝才有效。 

### 为什么它有效

 DP 状态准确捕获未来扩展所需的信息。 

假设我们知道以字母开头的最佳链$s$并以字母结尾$e$。 任何未来的字符串只能检查其第一个字母是否匹配$e$。 链条上的其他事情都不重要。 

当我们附加一个字符串时$a$到$b$，每个兼容链结束于$a$成为一条新链，结束于$b$，总长度增加当前字符串长度。 

因为每个字符串都被处理一次，并且转换仅按时间顺序前进，所以每个构造的链都对应于一个有效的国王子序列。 相反，每个有效的王朝都可以通过这些转变建立起来，因此DP永远不会错过最佳解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = -(10 ** 18)

n = int(input())

dp = [[INF] * 26 for _ in range(26)]

for _ in range(n):
    s = input().strip()

    a = ord(s[0]) - ord('a')
    b = ord(s[-1]) - ord('a')
    w = len(s)

    old = [dp[i][a] for i in range(26)]

    dp[a][b] = max(dp[a][b], w)

    for start in range(26):
        if old[start] != INF:
            dp[start][b] = max(dp[start][b], old[start] + w)

ans = 0

for i in range(26):
    ans = max(ans, dp[i][i])

print(ans)
```DP 表存储每个起始字母对的最佳可实现总长度。 无效状态用一个非常负的数字初始化，这样我们就可以将它们与合法链区分开来。 

对于每个字符串，我们首先提取其边界字母和长度。 该字符串总是可以自己形成一个王朝，因此我们更新`dp[a][b]`直接地。 

微妙的部分是安全地延长以前的链条。 我们必须避免读取在当前迭代期间已经更新的值，因为这将允许多次附加相同的字符串。 该行：```
old = [dp[i][a] for i in range(26)]
```创建所有以字母结尾的链的快照`a`在处理当前字符串之前。 

然后每个兼容链都会按当前字符串长度进行扩展。 

最后，只有起始字母和结束字母相等的国家才代表有效的朝代，因此我们取最大对角线值。 

## 工作示例

 ### 示例 1

 输入：```
3

ca
cba
```处理痕迹：

 | 字符串| 开始| 结束 | 长度 | 更新状态 |
 | ---| ---| ---| ---| ---|
 | ABC | 一个 | c | 3 | dp[a][c] = 3 | dp[a][c] = 3 |
 | 加州 | c | 一个 | 2 | dp[c][a] = 2, dp[a][a] = 5 |
 | 篮球协会| c | 一个 | 3 | dp[c][a] = 3, dp[a][a] = 6 |

 最终对角线值：

 | 状态| 价值|
 | ---| ---|
 | dp[a][a] | dp[a][a] | 6 |
 | 其他 | 无效或较小|

 回答：```
6
```最佳王朝使用`"abc"`其次是`"cba"`。 中间字符串`"ca"`被跳过。 这说明了为什么贪婪扩展是不够的以及为什么子序列 DP 是必要的。

 输入：```
2
ab
bc
```处理痕迹：

 | 字符串| 开始| 结束 | 长度 | 更新状态 |
 | ---| ---| ---| ---| ---|
 | ab | 一个 | 乙| 2 | dp[a][b] = 2 |
 | 公元前 | 乙| c | 2 | dp[b][c] = 2，dp[a][c] = 4 |

 最终对角线值：

 | 状态| 价值|
 | ---| ---|
 | dp[a][a] | dp[a][a] | 无效|

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(26 \cdot n)$| 每个字符串在 26 个可能的起始字母上执行转换 |
 | 空间|$O(26^2)$| DP表仅包含676个状态|

 和$n \le 5 \cdot 10^5$，该算法执行大约 1300 万次状态转换，这在 Python 中已经足够快了。 内存占用很小。

# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    INF = -(10 ** 18)

    n = int(input())

    dp = [[INF] * 26 for _ in range(26)]

    for _ in range(n):
        s = input().strip()

        a = ord(s[0]) - ord('a')
        b = ord(s[-1]) - ord('a')
        w = len(s)

        old = [dp[i][a] for i in range(26)]

        dp[a][b] = max(dp[a][b], w)

        for start in range(26):
            if old[start] != INF:
                dp[start][b] = max(dp[start][b], old[start] + w)

    ans = 0

    for i in range(26):
        ans = max(ans, dp[i][i])

    return str(ans)

# provided sample
assert run("3\nabc\nca\ncba\n") == "6", "sample 1"

# no valid dynasty
assert run("2\nab\nbc\n") == "0", "no cycle"

# single valid string
assert run("1\nc\n") == "1", "single string cycle"

# choose non-adjacent strings
assert run("4\nab\nbc\nca\naa\n") == "6", "best subsequence"

# all equal letters
assert run("3\naa\naa\naa\n") == "6", "all chains compatible"

# off-by-one style chain
assert run("3\nab\nba\nab\n") == "6", "reuse all strings correctly"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 |`1 / c`|`1`| 单弦王朝|
 |`2 / ab bc`|`0`| 不存在循环 |
 |`4 / ab bc ca aa`|`6`| 最佳答案可能会跳过字符串 |
 |`3 / aa aa aa`|`6`| 重复兼容状态 |
 |`3 / ab ba ab`|`6`| 正确的转换链接 |

 ## 边缘情况

 考虑单个字符串已经形成循环的情况。```
1
abca
```该字符串的开头和结尾为`a`，因此在处理过程中我们更新：```
dp[a][a] = 4
```最终对角线最大值变为 4，这是正确的。 仅扩展先前链的算法会错过这一点，因为不需要转换。 

现在考虑一种情况，其中跳过字符串是最佳的。```
3
abc
ca
cba
```加工后`"abc"`:```
dp[a][c] = 3
```加工`"ca"`创建：```
dp[a][a] = 5
```加工`"cba"`直接扩展之前的链：```
dp[a][a] = 6
```该算法自然会探索所有子序列，因为每个状态对于未来的转换都会持续存在。 

最后，考虑一个危险的就地更新场景。```
3
ab
bc
ca
```加工时`"bc"`，我们首先对所有以以下结尾的链进行快照`b`。 如果没有此快照，则更新`dp[a][c]`可能会意外地影响同一迭代和重用中的后续转换`"bc"`多次。 

使用：```
old = [dp[i][a] for i in range(26)]
```保证每个转换仅使用处理当前字符串之前存在的状态。
