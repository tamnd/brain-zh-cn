 ## 解决方案
 ## 问题理解

 我们得到了一个排成一行的数字数组。 两名玩家轮流进行，从爱丽丝开始。 在每次移动时，玩家都会删除最左边或最右边的剩余元素，并将其附加到正在构造的序列中。 唯一的限制是每次移动后结果序列必须保持严格递增。 做出最后有效动作的玩家获胜。 

该游戏不是为了最大化分数，而是为了在单调约束下生存。 每个选择都会删除一个端点并收紧允许的未来移动，因为下一个选择的值必须严格大于迄今为止选择的所有值。 

约束条件$N \le 2 \cdot 10^5$立即排除任何状态空间探索。 朴素博弈树的分支因子为 2，深度可达$N$，导致$2^N$国家，这是完全不可行的。 即使是在时间间隔内记忆的动态编程以及对最后选取值的状态跟踪也是有问题的，因为最后一个值并不小并且取决于连续范围内的历史记录。 

一些小的边缘情况已经暗示了结构：

 例如，如果所有元素都相等$A = [5, 5, 5]$，只有一次移动是可能的，因为在选择 5 之后，不存在进一步严格更大的元素。 游戏在第一步后立即结束，因此爱丽丝获胜。 

如果数组是严格递增的，比如说$A = [1,2,3,4]$，每一步都被迫从左或右选择，但任何选择都是有效的，因为两端始终保持递增顺序。 游戏变得纯粹是剩余动作的平价，而不是策略。 

当局部选择以不同的方式保留未来的灵活性时，就会出现贪婪直觉的微妙失败案例。 例如，采用较小的最终值并不总是最佳的，因为它可能会阻止将来访问继续序列所需的大值。 

## 方法

 暴力方法可以模拟所有可能的游戏。 在每个状态，我们考虑当前子数组$[l, r]$和最后选择的值。 如果我们选择任一端并且该值大于最后选择的值，则移动有效。 我们递归地判断当前玩家是否可以强行获胜。 这正确地模拟了游戏，但是状态的数量是指数级的$N$，甚至通过记忆来压缩$(l, r, last)$不可行，因为`last`取任意值，最多可达$10^9$，使得状态爆炸不可避免。 

关键的观察是，最佳游戏永远不需要记住比当前边界和序列如何演变的方向偏差更多的内容。 由于每次移动都会删除一个端点，因此该过程完全取决于可玩间隔如何缩小，同时尊重增加的约束。 关键的结构事实是，一旦玩家选择了一个值，所有未来的有效动作都必须严格位于该值之上，这强烈限制了哪一侧仍然有用。 这将游戏简化为带有强制分段的确定性收缩过程，其中唯一真正的决定是左选择还是右选择是否保留更长的有效延续。 

我们不是探索游戏状态，而是跟踪在最佳游戏下始终采用较小的有效端点时可以进行多少次连续强制移动。 游戏交替控制，但结构确保移动总数仅取决于在不断增加的条件强制终止之前这个贪婪一致的过程持续多长时间。 

这将问题转化为模拟两指针过程，其中玩家交替选择保持可行性的较小有效端点，并通过步数奇偶性确定获胜者。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 状态上的强力递归 | O(2^N) | O(2^N) | O(N) | 太慢了 |
 | 两指针贪心模拟| O(N) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们维护两个指针，$l$和$r$，最初位于数组的末尾。 我们还跟踪最后选择的值，最初设置为负无穷大。 布尔标志跟踪轮到谁了，但关键思想是两个玩家都遵循相同的最佳规则，因此我们只模拟由此产生的强制游戏。 

1. 初始化$l = 0$,$r = N - 1$， 和`last = -∞`。 将移动计数器设置为 0。 
2. 在每一步中，考虑有效的候选者$A[l]$和$A[r]$严格大于`last`。 如果两者都无效，则游戏停止。 
3. 如果两端都有效，则选择两个值中较小的一个。 这保留了灵活性，因为选择较小的值可以保留更多的未来选项来维护严格增加的属性。 
4. 如果只有一端有效，则取那一端。 
5. 更新`last`到所选值，向内移动相应的指针，并增加移动计数器。 
6. 重复直到不存在有效的移动。 
7、如果总步数是奇数，则Alice走的是最后一步； 否则鲍勃就这么做了。 

始终采用较小的有效端点背后的原因是，任何较大的早期选择只能减少未来有效扩展的集合，而不会增加它。 由于唯一的目标是最大化总移动次数，因此两个玩家都倾向于这种贪婪的行为。 

### 为什么它有效

 任何时刻，游戏状态完全由间隔决定$[l, r]$和最后选择的值。 任何有效的移动都会将间隔大小减少一并增加允许的未来值的下限。 在这两个端点中，就未来的可行性而言，选择较小的可行值优于较大的可行值，因为它对后续移动的约束较弱。 这会导致状态的单调演变，没有玩家可以从偏差中受益：每次偏差要么减少剩余的移动次数，要么保持不变，但给对手相同或更好的位置。 因此，贪婪模拟会产生最佳游戏下的准确移动次数，并且获胜者由奇偶性决定。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    l, r = 0, n - 1
    last = -10**18
    moves = 0

    while l <= r:
        left = a[l] if l <= r else None
        right = a[r] if l <= r else None

        valid_left = left is not None and left > last
        valid_right = right is not None and right > last

        if not valid_left and not valid_right:
            break

        if valid_left and valid_right:
            if left < right:
                last = left
                l += 1
            else:
                last = right
                r -= 1
        elif valid_left:
            last = left
            l += 1
        else:
            last = right
            r -= 1

        moves += 1

    print("Alice" if moves % 2 == 1 else "Bob")

if __name__ == "__main__":
    solve()
```该代码保持缩小间隔并通过以下方式强制增加约束`last`。 每次迭代根据贪心规则准确地解决一步，确保整个游戏的线性模拟。 奇偶性为`moves`直接决定胜负，因为爱丽丝先开始。 

一个常见的微妙之处是严格的不平等`> last`。 使用`>=`会错误地允许相同的元素并人为地扩展游戏。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(N) | 每个元素从两端都被删除一次 |
 | 空间| O(1) | O(1) | 仅维护指针和一些变量 |

 线性扫描是最佳的，因为每次移动都会永久删除一个元素，并且不会重新访问任何元素。 这完全符合以下限制$N \le 2 \cdot 10^5$。

 ## 边缘情况

 对于所有值都相等的数组，算法会立即取一个元素并终止，因为没有后续值严格大于`last`。 一次移动后，间隔就会崩溃，爱丽丝成为获胜者。 

对于严格递减的数组，例如`[5,4,3,2,1]`，贪心规则总是仅在有效时才取大端，这种情况只发生一次。 第一步之后，没有剩余元素超过所选值，因此游戏立即结束，爱丽丝再次成为获胜者。 

对于严格递增的数组，两端在每一步都保持有效，但算法始终删除元素直到耗尽。 这创建了一个确定性序列$N$移动，获胜者仅取决于奇偶性，鲍勃获胜$N$是均匀的。
