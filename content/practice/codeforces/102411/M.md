 ## 解决方案
 ## 问题理解

 我们有一个数组`a`描述连续几天发布的问题的难度。 我们需要选择三个索引`i < j < k`这样中间的难度正好是其他两个难度的一半：

 [
 a_j-a_i=a_k-a_j。 
]

 重新排列给出

 [
 a_i+a_k=2a_j。 
]

 因此，任务是计算每个索引三元组，其三个困难按其原始数组顺序形成算术级数。 值本身不需要不同，共同差可以是正数、零或负数。 

最多有`n = 2000`职位。 三次算法检查

 [
 \binom{2000}{3}=1,331,334,000
 ]

 最大测试用例中的三倍。 由于测试用例多达 10 个，且时间限制为 2 秒，这样的工作量远远超出了 Python 的处理能力。 另一方面，二次解的性能约为

 [
 \binom{2000}{2}=1,999,000
 ]

 每个测试用例的内部迭代，这是实用的。 

这些值可以大到 (10^9)，因此表达式`2 * a[j] - a[k]`大约可以达到 (2\cdot10^9) 的大小。 Python 整数直接处理这个问题，而具有固定宽度整数类型的语言应该使用足够宽的有符号类型。 答案本身的值可以超过 (10^9)，达到 (1,331,334,000)，因此 32 位有符号整数在这里仍然足够，尽管 64 位整数是常规选择。 

一种微妙的情况是重复值。 例如，与`a = [5, 5, 5, 5]`，三个位置的每一个选择都有效，所以答案是 4。如果不小心实现，只存储某个值是否存在，而不存储它出现的次数，就会丢失多重性并导致计数不足。 

另一种情况是零或负公差。 为了`a = [30, 20, 10]`，唯一的三元组有差异`-10`和`-10`，所以答案是 1。假设数组必须增加或仅检查正差的方法将错误地返回零。 

第三种情况是前缀中不存在所需的值。 为了`a = [1, 1, 2]`，取中间位置给出`2 * 1 - 2 = 0`，但没有较早的零，因此答案为 0。查找必须允许任意目标值，并且当目标不存在时仅返回零。 

最后，索引的顺序很重要。 为了`a = [1, 2, 1]`，这些值是包含等差数列的集合，但唯一可能的三元组有差异`1`和`-1`，所以答案是 0。在不考虑原始索引顺序的情况下计算值组合会产生错误的结果。 

## 方法

 直接的解决办法是枚举每一个可能的三元组`i < j < k`并测试是否`a[i] + a[k] == 2 * a[j]`。 这是正确的，因为每个有效答案都是这样的三元组，并且满足该方程的每个三元组都只计算一次。 问题是三元组的数量。 为了`n = 2000`，正好有 1,331,334,000 个，这使得三次枚举太慢。 

有用的观察来自固定中间索引`j`。 一次`j`和正确的端点`k`是固定的，所需的左值不再是未知的。 来自

 [
 a_i+a_k=2a_j
 ]

 我们得到

 [
 a_i=2a_j-a_k。 
]

 所以对于每个位置`k > j`，我们只需要知道有多少个较早的位置`i < j`包含值`2 * a[j] - a[k]`。 

这将问题转化为频率查找问题。 从左到右处理位置时，维护一个频率图，其中包含当前中间位置之前位置的值。 对于每一个可能的`k`在右侧，计算左侧所需的值并将其频率添加到答案中。 

蛮力之所以有效，是因为它明确地检查了每个可能的三元组，但由于三元组太多而失败。 一个端点可以从另外两个端点确定，这一观察结果让我们用 (O(1)) 平均哈希映射查找替换最内层循环。 我们仍然考虑涉及中间位置的每一对，给出 (O(n^2)) 算法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(1) | O(1) | 太慢了|
 | 最佳 | 预计 O(n²) | O(n) | 已接受 |

 ## 算法演练

 1. 创建一个空的频率图`freq`。 它将严格存储当前中间位置之前每个难度出现的次数。 
2. 迭代可能的中间索引`j`从左到右。 在本次迭代开始时，`freq`恰好包含索引小于的元素`j`。 
3. 对于每个位置`k > j`, 计算

 [
 目标=2a_j-a_k。 
]

 任何有效的左索引`i`必须满足`a[i] = target`，所以这个特定的有效选择的数量`j`和`k`正是`freq[target]`。 
4. 添加`freq[target]`每个问题的答案`k`向右。 频率查找一次计算所有有效的左索引，包括不同位置的重复值。 
5. 处理完每个右侧位置后，插入`a[j]`进入`freq`。 必须在加工后插入`j`， 因为`j`不允许在同一迭代中充当稍后的右端点的其自己的左端点。 
6. 处理完所有可能的中间位置后，输出累加的答案。 

### 为什么它有效

 不变量是在处理中间索引之前`j`,`freq[x]`等于索引的数量`i < j`为此`a[i] = x`。 对于每一个`k > j`，等差数列条件等价于`a[i] = 2a[j] - a[k]`。 该算法精确地添加了此类较早索引的数量，因此每个具有中间索引的有效三元组`j`被计算在内。 由于每个三元组只有一个中间索引，因此不会对任何三元组进行多次计数。 加工后`j`，添加`a[j]`恢复下一个中间索引的不变量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    answers = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        freq = {}
        ans = 0

        for j in range(n):
            middle = a[j]

            for k in range(j + 1, n):
                target = 2 * middle - a[k]
                ans += freq.get(target, 0)

            freq[middle] = freq.get(middle, 0) + 1

        answers.append(str(ans))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```外循环选择中间索引`j`，匹配算法的第一步。 在循环开始之前，`freq`为空，因为索引零之前没有位置。 

对于固定的`j`，内循环访问每个`k > j`。 表达式`2 * middle - a[k]`正是之前的值`a[i]`必须有三元组才能形成算术级数。`freq.get(target, 0)`给出了此类较早位置的数量，因此添加它会计算所有兼容的选择`i`立刻。 

更新至`freq`发生在内循环之后。 这个顺序是必要的，因为`freq`必须代表严格小于`j`。 如果`a[j]`首先插入，当前的中间位置可能会被错误地算作左端点。 

范围`range(j + 1, n)`强制执行`k > j`，而频率图已经强制执行`i < j`。 因此，所有三个索引的严格排序直接构建到迭代结构中。 

Python 的字典提供了预期的 (O(1)) 插入和查找，这给出了二次预期运行时间。 Python 整数在计算时也可以避免溢出`2 * middle - a[k]`或存储答案。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 预计 O(n²) | 每对`(j, k)`和`j < k`检查一次，每个字典操作预计为 O(1)。 |
 | 空间| O(n) | 频率映射对于前缀中的每个不同难度最多存储一个条目。 |

 为了`n = 2000`，内循环对于一个测试用例最多执行 1,999,000 次迭代。 即使有最大大小的 10 个测试用例，这也大约是 2000 万次字典查找，这适合典型优化的 Python 提交中的两秒限制。 内存使用最多是线性的`n`，远低于 512 MB 限制。

 ## 边缘情况

 对于重复值的情况，考虑`a = [5, 5, 5, 5]`。 四个可能的三元组中的每一个都是有效的，因此输出为 4。处理时`j = 2`，例如，频率图包含两个较早出现的`5`。 正确的端点`k = 3`需要`target = 2 * 5 - 5 = 5`，因此该算法为两个可能的左端点加 2。 早期的迭代贡献了另外两个三元组。 最终答案恰好是4。 

对于负公差，请考虑`a = [30, 20, 10]`。 在`j = 1`，右端点的值为 10，给出`target = 40 - 10 = 30`。 前缀包含 1 个 30，因此算法会加 1。 答案是 1。计算中任何地方都不存在关于增加值的假设。 

对于不存在的目标，请考虑`a = [1, 1, 2]`。 在`j = 1`，目标为`k = 2`是`2 * 1 - 2 = 0`。 频率图仅包含`{1: 1}`， 所以`freq.get(0, 0)`返回零。 该算法产生 0，正确拒绝唯一可能的三元组。 

对于顺序敏感的情况，请考虑`a = [1, 2, 1]`。 在`j = 1`,`k = 2`需要左值为`2 * 2 - 1 = 3`。 前缀仅包含`1`，所以什么都不算。 答案是 0。虽然这些值包含`1, 2, 1`，它们的连续差为`1`和`-1`，因此它们没有形成所需的算术级数。 

最大答案的情况是`n = 2000`每个值都等于`1`。 三个指数的每一个选择都有效，给出

 [
 \binom{2000}{3}=1,331,334,000。 
]

 该算法通过频率对这些组合进行计数，而不是单独枚举它们，这正是为什么即使有效三元组本身的数量超过十亿，二次方法仍然保持快速的原因。
