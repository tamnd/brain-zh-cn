 ## 解决方案
 ## 问题理解

 我们需要选择一个整数中心`(X, Y)`和一个整数高度`H`对于轴对齐的四棱锥。 因为每条边都有精确的坡度`45°`，从中心水平或垂直移动一个单位会使金字塔降低一个单位。 因此，在位置`(x, y)`，金字塔的高度是

 [
 H-\max(|x-X|,|y-Y|)。 
]

 方尖碑`(x_i, y_i, h_i)`如果其高度不超过该值，则适合。 任务是找到一个包含每个方尖碑的尽可能最小高度的金字塔，并输出达到该最小值的任何中心。 

输入最多包含`1000`方尖碑。 他们的坐标和高度可以达到`10^8`在大小上，因此枚举可能的坐标是完全不可行的。 一个坐标可以大致有`2 * 10^8`可能的值，大致给出`4 * 10^16`可能的中心。 和`1000`方尖碑，检查所有方尖碑需要大约`4 * 10^19`基本检查。 该解决方案需要基本上线性地处理输入。 

整数限制也很重要。 连续的几何最佳值是不够的，因为中心和高度必须是整数。 幸运的是，相关约束都是整数区间，因此无需浮点运算即可获得精确的整数最优值。 

有几种边缘情况可能会导致粗心的解决方案失败。 凭借一个方尖碑，```
1
0 0 5
```答案是`0 0 5`。 盲目地尝试将中心放置在极端坐标之间的中间的方法可能会意外地增加高度，即使将其直接放置在方尖碑下方是最佳的。 

一个更有趣的边界情况是```
2
0 0 1
2 0 1
```正确答案可以是```
1 0 2
```因为金字塔有高度`2`，并且两个方尖碑距离中心正好一个单位。 最佳中心的区间在单个整数点处闭合。 使用严格的不平等而不是包容性的不平等会错误地拒绝这个解决方案。 

不同的尺寸也可能需要不同的高度。 例如，```
2
0 0 100
10 0 1
```具有最佳高度`100`，有中心`(0, 0)`。 尽管第二个方尖碑距离很远，但非常高的第一个方尖碑主导了答案。 将所有方尖碑视为具有相同高度会产生错误的结果。 

最后，必须在不假设坐标非负的情况下处理大负坐标。 为了```
2
-100000000 -100000000 1
100000000 100000000 1
```最佳高度是`100000001`， 和`(0, 0)`是一个有效的中心。 Python 整数自然地处理这个范围，而固定宽度的实现需要足够宽的整数类型。 

## 方法

 直接方法将枚举候选中心`(X, Y)`。 对于每个中心，我们可以计算所需的最小高度：

 [
 \max_i\left(h_i+\max(|x_i-X|,|y_i-Y|)\right)。 
]

 这是正确的，因为每个方尖碑独立地告诉我们该中心所需的最小高度。 然而，大约有`4 * 10^16`坐标范围内的整数中心，并检查`1000`每个方尖碑大致给出`4 * 10^19`最坏情况下的操作。 时间限制立即排除了这一点。 

有用的观察隐藏在`max`。 我们可以重写

 \max(h_i+|x_i-X|,\h_i+|y_i-Y|)。 
]

 取所有方尖碑的最大值给出

 [
 H=
 \最大\左(
 \max_i(h_i+|x_i-X|),
 \max_i(h_i+|y_i-Y|)
 \右）。 
]

 两个坐标已经完全分开了。 我们可以独立确定所需的最小高度`x`坐标和为`y`坐标，然后取两个高度中较大的一个。 

仅考虑一个维度。 我们有岗位`c_i`, 高度`h_i`，并想要最小的整数`H`其中某个整数中心`C`满足

 [
 h_i+|c_i-C|\le H
 ]

 对于每一个`i`。 重新排列给出

 [
 c_i+h_i-H\le C\le c_i-h_i+H。 
]

 因此，每个方尖碑都给出了允许的间隔`C`。 当这些区间有一个公共点时，所有方尖碑都可以被精确地满足。 

定义

 [
 L=\max_i(c_i+h_i),
 \qquad
 R=\min_i(c_i-h_i)。 
]

 相交所有区间后，可能的中心恰好是

 [
 [L-H，\R+H]。 
]

 当这个区间非空时

 [
 L-H\le R+H，
 ]

 或

 [
 2H\ge从左到右。 
]

 因此该坐标所需的最小整数高度为

 [
 H_{\text{dim}}=\left\lceil\frac{L-R}{2}\right\rceil。 
]

 我们计算一次`x`一次`y`。 金字塔必须满足两个尺寸，因此其最小高度是这两个值中的最大值。 一旦知道了该高度，每个结果区间中的任何整数点都是有效的中心。 选择左端点，`L-H`，很方便并避免任何舍入问题。 

蛮力方法之所以有效，是因为它明确地评估了每个可能的中心。 它失败了，因为坐标空间巨大。 观察结果表明`max`分离成独立的`x`和`y`项将几何问题简化为两个一维区间交集，每个交集都可以一次性处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(n · C²)`在哪里`C`是坐标范围 |`O(n)`| 太慢了|
 | 最佳 |`O(n)`|`O(n)`用于存储输入，或`O(1)`超越它| 已接受 |

 ## 算法演练

 1. 阅读所有方尖碑。 对于`x`维度，计算

 [
 L_x=\max_i(x_i+h_i)
 ]

 和

 [
 R_x=\min_i(x_i-h_i)。 
]

 这两个值描述了金字塔高度固定后所有可能的中心区间的交集。 
2. 计算相同的量`y`尺寸：

 [
 L_y=\max_i(y_i+h_i),
 \qquad
 R_y=\min_i(y_i-h_i)。 
]

 这两个维度可以独立处理，因为金字塔所需的高度是两个坐标中要求的最大值。 
3. 求出所需的最小高度`x`尺寸：

 [
 H_x=\left\lceil\frac{L_x-R_x}{2}\right\rceil。 
]

 对于整数值，计算如下`(L_x - R_x + 1) // 2`。 
4. 找到对应的值`y`尺寸：

 [
 H_y=\left\lceil\frac{L_y-R_y}{2}\right\rceil。 
]
 5. 设置

 [
 H=\max(H_x,H_y)。 
]

 这个高度对于两个维度来说都是足够的，并且不能减小，因为两个维度之一已经需要至少这么多的高度。 
6. 选择

 [
 X=L_x-H,
 \qquad
 Y=L_y-H。 
]

自从`H >= H_x`和`H >= H_y`，这些值属于各自的可行区间。 它们是整数，因为涉及的每个数量都是整数。 
7. 输出`X`,`Y`， 和`H`。 生成的金字塔包含所有方尖碑，并且高度较小的金字塔无法包含所有方尖碑。 

### 为什么它有效

 对于任何固定高度`H`, 方尖碑`(c_i,h_i)`在一维中精确地允许中心间隔`[c_i+h_i-H, c_i-h_i+H]`。 所有这些区间的交集是`[L-H,R+H]`，因此有效中心恰好存在于`2H >= L-R`。 因此`H_x`和`H_y`是两个坐标强制的确切最小高度。 

完整的金字塔同时需要两个一维不等式。 由于其高度要求是独立的最大`x`和`y`的要求，全局最优正是`max(H_x,H_y)`。 选择`L_x-H`和`L_y-H`将中心放置在两个可行的交叉点内，因此每个方尖碑都被包含在内，同时高度最小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    lx = -10**30
    rx = 10**30
    ly = -10**30
    ry = 10**30

    for _ in range(n):
        x, y, h = map(int, input().split())

        lx = max(lx, x + h)
        rx = min(rx, x - h)

        ly = max(ly, y + h)
        ry = min(ry, y - h)

    hx = (lx - rx + 1) // 2
    hy = (ly - ry + 1) // 2

    H = max(hx, hy)

    X = lx - H
    Y = ly - H

    print(X, Y, H)

if __name__ == "__main__":
    solve()
```四个变量`lx`,`rx`,`ly`， 和`ry`维持区间交点所需的极值。 例如，`lx`商店最大的`x_i + h_i`，因为每个可行中心必须至少`x_i + h_i - H`。 

表达式`x + h`和`x - h`应按该顺序保存。 反转其中一个会改变表示可行区间的哪一侧并导致不正确的中心。 

上限划分是另一个容易出现差一错误的地方。 对于非负整数`d`,`ceil(d / 2)`是`(d + 1) // 2`。 这里`L - R`总是非负的，因为对于每个方尖碑，`x_i + h_i > x_i - h_i`，并且相同的顺序在取最大值和最小值时仍然存在。 

没有浮点计算。 精确的整数几何就足够了，Python 的任意精度整数可以轻松处理所有中间值。 最大的相关表达式的顺序是`2 * 10^8`，因此在具有固定宽度整数的语言中，即使是带符号的 64 位整数也足够了。 

该代码不需要存储方尖碑。 每个仅对四个运行极值有贡献，因此实现可以在一次传递中处理输入。

### 示例 2

 方尖碑是`(3,3,3)`和`(6,6,2)`。 

| 方尖碑|`x+h`|`x-h`|`y+h`|`y-h`|
 | ---| ---| ---| ---| ---|

 |`(6,6,2)`|`8`|`4`|`8`|`4`|

| 变量| 价值|

 | 时间 |`O(n)`| 每个方尖碑更新四个极值一次。 |
 | 空间|`O(1)`| 仅维护四个极值，不包括输入存储。 |

 ## 边缘情况

 单方尖碑案例```
1
0 0 5
```产生`lx = ly = 5`和`rx = ry = -5`。 两个一维最小高度均为`(5 - (-5) + 1) // 2 = 5`。 所选的中心是`5 - 5 = 0`在两个维度上，给出`0 0 5`。 该算法不依赖于多个方尖碑来形成间隔。 

精确边界情况```
2
0 0 1
2 0 1
```给出`lx = 3`和`rx = -1`。 所需的`x`高度是`(3 - (-1) + 1) // 2 = 2`。 在高处`2`, 可行的`x`间隔是`[3-2,-1+2] = [1,1]`，所以唯一可能的中心是`X=1`。 这`y`尺寸只需要高度`1`，所以最终高度仍然是`2`。 这会捕获意外使用楼层划分的实现。 

对于不等高的情况```
2
0 0 100
10 0 1
```这`x`极值是`100`和`-100`, 要求高度`100`，而`y`极值也是`100`和`-100`，但中心计算结果给出`(0,0)`。 在该中心，第一座方尖碑恰好达到高度`100`，而第二个有可用高度`90`，这远远超过了其所需的高度`1`。 高大的方尖碑决定了最小值。 

对于坐标边界情况```
2
-100000000 -100000000 1
100000000 100000000 1
```我们得到`L_x = L_y = 100000001`和`R_x = R_y = -100000001`。 因此`H = (100000001 - (-100000001) + 1) // 2 = 100000001`。 所选的中心是`0,0`。 每个方尖碑都准确无误`100000000`相关坐标中的单位距离，留下高度`1`，因此两者都恰好包含在边界处。 

最大尺寸测试`1000`相同的方尖碑在不改变数学结构的情况下练习输入边界。 在第一个方尖碑之后，每次更新都会使四个极值保持不变，因此最终答案保持不变。 这说明了为什么重复点不需要任何特殊处理以及为什么线性扫描仍然有效。
