 ## 解决方案
 ## 问题理解

 我们得到了运动员完成的一系列比赛距离。 根据这个序列，我们要计算他的“水平”，其中水平$K$意味着至少存在$K$其距离至少为$K$，并且运动员必须至少参加过$K$总共有这样的比赛。 

所以对于固定的候选值$K$，我们正在检查数组的阈值条件：有多少元素大于或等于$K$。 如果该计数至少为$K$，然后水平$K$是可以实现的。 

输出是这样的最大值$K$。 换句话说，我们正在寻找数量条件和价值条件都匹配的最大阈值：至少$K$元素至少为$K$。 

输入大小可达$10^5$，距离达到$10^9$。 这立即排除了尝试所有配对或重新计算每个候选者计数的任何解决方案$K$以一种天真的方式。 

蛮力方法会尝试每一个$K$从 1 到$n$，并为每一个扫描整个数组以计算有多少元素满足$a_i \ge K$。 那是$O(n^2)$在最坏的情况下工作，大约是$10^{10}$最大输入大小的操作，远远超出 2 秒的限制。 

当值很小但重复密集时，会出现微妙的边缘情况。 例如，如果所有值均为 1 并且$n = 5$，那么只有$K = 1$有效，而任何更大的事情都会失败。 如果混淆了条件（计算值），幼稚的实现可能会错误地假设错误方向的单调性$> K$而不是$\ge K$，或者忘记了第二个约束，即计数本身必须至少是$K$）。 

## 方法

 蛮力法很简单：测试每个候选级别$K$，计算至少有多少个元素$K$，并检查该计数是否达到$K$。 这是有效的，因为它直接对定义进行编码。 失败点是性能，因为每次检查都是线性的并且有$O(n)$检查。 

关键的观察是，我们只需要知道有多少元素超过每个阈值，一旦数组排序，这些查询就会变得高效。 排序后，大于等于的元素个数$K$只是排序数组中的后缀长度。 这会将每个计数查询在预处理后转换为恒定时间计算。 

因此，排序将问题转化为阈值搜索，其中每次检查都是$O(1)$，将整体复杂度降低到$O(n \log n)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了|
 | 排序+扫描阈值|$O(n \log n)$|$O(1)$或者$O(n)$| 已接受 |

 ## 算法演练

 我们首先对数组进行排序，以便所有大值都分组在末尾。 

1. 对数组进行非降序排序。 这使我们能够通过查看位置而不是扫描来快速计算有多少元素至少是给定值。 
2. 将答案变量初始化为零。 这将跟踪迄今为止发现的最佳有效级别。 
3. 迭代可能的值$K$从 1 到$n$。 上限是$n$因为一个级别$K$至少需要$K$元素。 
4. 对于每个$K$，找出至少有多少个元素$K$。 在排序数组中，这相当于查找值达到的第一个索引$K$，然后计算后缀长度。 
5. 如果此计数至少为$K$，更新答案。 
6.检查完所有候选后，输出最大有效值$K$。 

关键的设计选择是我们永远不会通过扫描数组来重新计算计数。 相反，排序将所有频率信息隐式编码在索引位置中。 

### 为什么它有效

 排序后，条件“至少$K$元素是$\ge K$” 仅取决于从第一个值开始后缀中有多少个元素$\ge K$。 这将每个候选检查减少为排序顺序的确定性函数。 每个有效$K$在排序下保留，因为排序不会更改元素值，只会更改元素的位置，并且条件仅取决于高于阈值的计数，而不取决于排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [int(input()) for _ in range(n)]
    
    a.sort()
    
    ans = 0
    for k in range(1, n + 1):
        # find first index with value >= k
        lo, hi = 0, n
        while lo < hi:
            mid = (lo + hi) // 2
            if a[mid] >= k:
                hi = mid
            else:
                lo = mid + 1
        
        cnt = n - lo
        if cnt >= k:
            ans = k
    
    print(ans)

if __name__ == "__main__":
    solve()
```该实现依赖于排序，然后对每个候选进行二分搜索$K$。 二分查找查找小于的值之间的边界$K$和值至少$K$，后缀长度直接给出计数。 唯一的微妙之处是在二分搜索中保持正确的不等式方向； 混合起来`>=`和`>`会改变边界并破坏正确性。

 ## 边缘情况

 一种棘手的情况是只有一个值较大而其余值都很小。 对于输入如：```
4
1
1
1
10
```该算法正确地发现$K \ge 2$，后缀大小变为1，这是不够的。 二分查找仍然可以识别出正确的边界，并且检查`cnt >= k`防止高估水平。 

另一个边缘情况是所有值都完全等于$n$。 在这种情况下，每个$K \le n$有效，因为后缀大小始终保持不变$n - first_index = n$。 该算法不断更新答案$n$，正确返回最大可能级别。
