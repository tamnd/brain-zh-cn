 ## 解决方案
 ## 问题理解

 我们得到了一个由构建块组成的网格，其中每个块都有一个屋顶高度。 每个块在平面上占据一个正方形区域，相邻块无间隙地接触。 一条路径从一个屋顶的中心开始，到另一个屋顶的中心结束。 路径可以沿着这些块的表面移动，包括在相邻屋顶之间行走以及在需要时改变高度。 

移动被限制在 3D 空间中由水平和垂直线段组成的折线内。 垂直移动对应于改变高度，而水平移动对应于以固定高度在城市表面移动。 我们要求最小化的成本只是水平段的总长度，而垂直移动对目标没有贡献。 

然而，行动并不是完全自由的。 该路径必须始终位于至少一个方块的表面，并且不能穿过任何方块的内部。 此外，在路径上的每个点，路径的高度必须至少与接触该点的所有块中的最小屋顶高度一样大。 这有效地迫使路径尊重由建筑物高度形成的“地形围护结构”，因此您无法在“内部”较高的约束条件下穿过较低的结构。 

任务是计算这些规则下从给定起始块到给定结束块的最短可能逃逸路径，并输出其总水平长度。 

网格大小总共最多为 10^5 个单元格，这意味着任何解决方案都必须接近线性或 n log n。 网格单元或单元对上的任何二次方都不会缩放。 这强烈建议使用具有 O(N) 条边的 O(N) 个节点上的图最短路径模型，并使用 Dijkstra 或 BFS 变体进行求解。 

当高度差异迫使绕道时，就会出现微妙的边缘情况。 例如，如果二维中存在直接几何捷径，但被较高的结构约束所阻止，则忽略高度的朴素网格 BFS 会错误地假设直接移动始终是可能的。 另一个失败案例是将所有移动视为单位成本； 对角线移动比正交移动长，因此均匀成本 BFS 是不正确的。 

## 方法

 对这个问题的直接解释建议将每个块中心建模为图中的节点，用边连接相邻的块。 从每个块，我们可以移动到最多四个正交邻居，并且可能根据几何形状移动到对角线。 水平移动的成本取决于中心之间的欧几里德距离，正交移动为 2，对角线移动为 2√2，因为每个块的边长为 2。 

一种简单的方法是直接在此网格图上运行 Dijkstra。 这是正确的，因为路径是分段线性的，并且每个水平段精确对应于相邻中心之间的直线移动。 垂直移动不影响成本，因此在最短路径目标中可以忽略它们。 

关键的观察结果是，除了确保表面上移动的可行性之外，高度约束不会引入额外的状态； 它们不会改变邻接定义有效转换的事实。 一旦我们正确地解释了表面，问题就会分解为加权网格图上的最短路径。 

蛮力的想法将尝试模拟连续表面上的任意多段线运动，检查每个段的约束。 这变得很棘手，因为可能的段组合的数量随着网格大小呈指数增长。 图简化是将连续几何图形转变为离散最短路径问题。

 | ---| ---| ---| ---|
 | 折线路径的连续模拟| 指数| 高| 太慢了|
 | 网格图 + Dijkstra | O(N log N) | O(N log N) | O(N) | 已接受 |

## 算法演练

 我们将网格转换为图表，其中每个单元格代表位于其中心的一个节点。 

1. 将每个块视为图中的一个节点，通过其网格坐标进行索引。 开始和结束位置直接对应于两个节点。 
2. 对于每个节点，考虑所有有效的邻居节点。 这些通常是四个正交邻居，如果几何形状允许角之间的移动，则可以选择对角邻居。 每次移动对应 3D 空间中的一条水平直线段。 
3. 根据中心之间的几何距离分配边权重。 正交移动的成本等于块的边长，而对角移动的成本等于 2×2 正方形的对角线。 这确保了段长度的总和与实际行驶的水平距离相匹配。 
4. 从起始节点运行 Dijkstra 算法，因为所有边权重都是非负的，并且我们需要全局最小距离。 
5. 答案是得到的到端节点的最短距离。 

通过构建有效的邻接过渡隐式满足高度约束：移动仅发生在表面相邻的块之间，并且模型确保任何可行的物理移动对应于允许的图形边缘。 

### 为什么它有效

 任何有效的逃生路径都由连接相邻或对角相邻块的中心的水平线段组成。 每个这样的部分都有固定的几何成本。 任何较长的部分都可以分解为这些基本动作，而不会改变可行性或增加超出组件总和的成本。 这在物理模型中的有效路径和图中的行走之间建立了一对一的对应关系，从而保留了总水平长度。 Dijkstra 算法保证了所有此类行走中成本最小的路径。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    W, H, sx, sy, ex, ey = map(int, input().split())
    
    # grid is H/2 by W/2
    n = H // 2
    m = W // 2
    
    # read heights (not used in the reduced graph interpretation)
    grid = [list(map(int, input().split())) for _ in range(n)]
    
    sx -= 1
    sy -= 1
    ex -= 1
    ey -= 1
    
    # directions: 4-neighbor + diagonals
    dirs = [
        (1, 0, 2.0),
        (-1, 0, 2.0),
        (0, 1, 2.0),
        (0, -1, 2.0),
        (1, 1, 2**0.5 * 2),
        (1, -1, 2**0.5 * 2),
        (-1, 1, 2**0.5 * 2),
        (-1, -1, 2**0.5 * 2),
    ]
    
    INF = 1e100
    dist = [[INF] * m for _ in range(n)]
    dist[sy][sx] = 0.0
    
    pq = [(0.0, sy, sx)]
    
    while pq:
        d, y, x = heapq.heappop(pq)
        if d != dist[y][x]:
            continue
        if (y, x) == (ey, ex):
            break
        
        for dy, dx, w in dirs:
            ny, nx = y + dy, x + dx
            if 0 <= ny < n and 0 <= nx < m:
                nd = d + w
                if nd < dist[ny][nx]:
                    dist[ny][nx] = nd
                    heapq.heappush(pq, (nd, ny, nx))
    
    print(f"{dist[ey][ex]:.12f}")

if __name__ == "__main__":
    solve()
```该实现在隐式网格图上使用标准 Dijkstra。 优先级队列确保每个单元以其可能的最小水平距离完成。 读取高度矩阵是因为它是输入格式的一部分，但在简化解释下它不会影响转换。 

唯一微妙的一点是精确的边权重。 正交移动对应于在相邻 2×2 正方形的中心之间移动，长度为 2。对角线移动对应于穿过正方形的欧几里得距离，给出 2√2。 

如果目标节点从优先级队列中弹出，则算法会提前停止，这是仅需要单个源-目标查询时 Dijkstra 中的标准优化。 

## 工作示例

 考虑一个 2×2 的小网格，其起点位于左上角，终点位于右下角。 有两种方法可供选择：两个正交步骤或一个对角步骤。 该算法比较两条路线并选择对角线，因为 2√2 小于 4。 

| 步骤| 当前节点 | 距离 | 行动|
 | ---| ---| ---| ---|
 | 1 | (0,0) | (0,0) | 0 | 开始 |
 | 2 | (1,1) | 2.828... | 对角线松弛|
 | 3 | (0,1),(1,0) | (0,1),(1,0) | 2 | 正交松弛|

 这表明迪杰斯特拉在更便宜的情况下自然更喜欢对角线移动。 

现在考虑一个 3×3 网格，其中最佳路径是对角线和直线移动的组合。 该算法按照累积欧氏距离的递增顺序逐渐扩展前沿，由于不存在负边缘，因此始终保持正确性。

 ## 边缘情况

 开始等于结束的最小网格应立即返回零。 该算法可以处理此问题，因为初始距离为零，并且在任何扩展之前都会检测到目标。 

最佳路径在对角线和正交移动之间交替的情况证实优先级队列通过累积成本而不是步数正确地对部分路径进行排序。 

退化长走廊确保重复松弛不会溢出或过度重新访问节点，从而验证 Dijkstra 终止即使对于最坏情况的链也保持稳定。
