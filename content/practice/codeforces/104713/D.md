 ## 解决方案
 ## 问题理解

 我们得到一个无向图，它是一棵最多有 100 个顶点的树。 少量“侦探”被放置在顶点上。 每天，攻击者都会宣布他们计划“攻击”的一个顶点。 看到目标后，每个侦探最多可以沿着一条边移动。 所有移动结束后，如果至少有一名侦探结束在被攻击的顶点，则攻击被阻止； 否则攻击者立即获胜。 这个过程最多重复 365 轮，防守者的目标是避免在这些轮次内失败。 

防守方可以选择侦探的初始位置，之后每轮只能进行一步移动。 攻击者具有完全的适应性并且了解一切，因此覆盖范围或移动性方面的任何弱点都可以被利用。 

图结构是具有特殊约束的树：没有顶点的度数恰好为 2。 这很重要，因为它消除了控制可以缓慢传播的长“链条”； 每个非叶顶点都以有意义的方式分支。 

塑造一切的关键约束是运动规则。 侦探无法传送。 如果侦探距离宣布的目标很远，可能根本不可能一步到达，因此防御者唯一的希望就是始终保持对每个可能目标的即时局部覆盖。 

一个微妙的边缘情况是没有侦探。 在这种情况下，攻击者在第一步就轻松获胜，因为没有顶点可以被占据。 

另一个边缘情况是叶子较多的树。 例如，如果一个顶点连接到许多叶子，则放置在该中心顶点上的单个侦探可以同时保护所有叶子，但如果叶子分布在许多不同的父节点上，则每个这样的区域可能需要自己的专用侦探。 “一个侦探最终可以漫游到任何地方”的天真想法失败了，因为攻击者每轮都会敌对地选择目标，而不是单一路径。 

## 方法

 暴力解释试图模拟整个互动游戏。 人们可能会尝试跟踪所有侦探位置，并针对每个可能的攻击者移动，计算是否存在一系列有效的单步移动，使至少一名侦探保持在目标上。 这很快就会成为大小配置的可达性问题$O(B^D)$，因为每个侦探都可以在任何地方。 即使是为了$B = 100$，这会立即爆炸并且无法计算。 

重要的转变是停止考虑完整的配置，而是专注于防守单轮意味着什么。 在任何一轮中，当且仅当移动后至少有一名侦探恰好落在被攻击的顶点上时，防御者才会成功。 这意味着在移动之前，距离目标最多一距离处必须已经有一名侦探，否则没有人能够及时到达目标。 

因此，每一轮都简化为一个简单的几何条件：侦探位置集必须形成图中的主导集，这意味着每个顶点要么被占用，要么与侦探相邻。 真正的困难不仅在于维持统治地位，还在于能够在统治配置之间进行转换，同时仍然保持该属性针对任意未来目标。 

在没有二阶顶点的树上，支配与有效覆盖叶子密切相关。 放置在至少三度内部顶点的侦探可以同时保护所有相邻的叶子，因为每个这样的叶子的距离为一。 叶子本身的单独防御成本很高，因为它们只能保护自己和单个邻居。 

这引出了关键的结构思想：瓶颈在于存在多少个叶区域无法共享附近的单个防御者。 最佳策略本质上是为每个“叶簇”分配至少一名侦探，并且此类簇的数量恰好等于该受限树结构中叶子的数量。 如果有足够的侦探覆盖所有叶子，防御者就可以保持稳定的覆盖，以抵御任意攻击。 

如果没有足够的侦探，攻击者可以反复选择未覆盖的叶子或在远处的叶子之间强制振荡，最终形成一个目标不与任何侦探相邻的回合。

 ## 算法演练

 ### 算法演练

 1. 读取树并计算每个顶点的度数。 这可以识别哪些顶点是叶子，哪些是需要直接保护的结构端点。 
2. 计算有多少个顶点的度数等于 1。 这些是叶子，它们代表了独立“危险点”的最小数量，除非它们共享邻居，否则单个侦探无法全部覆盖这些“危险点”。 
3.比较侦探的数量$D$与叶子的数量$L$。 如果$D \geq L$，选择防守角色。 否则，选择攻击。 
4. 如果是防守，首先将侦探放在任何有效的一组上$D$顶点。 一个安全的规范选择是在每片叶子上放置一名侦探，直到所有侦探都放置完毕。 
5. 游戏过程中，任意响应，同时保持每片叶子与至少一名侦探相邻或被一名侦探占据的不变量。 由于每个叶子在结构上都与其父叶子隔离（不存在二级链），因此在任何单步移动下都可以保持这种覆盖范围。 
6. 如果进攻，除了选择“进攻”之外，不需要额外的逻辑，因为目标是迫使防守者在移动限制下无法保持完全树叶覆盖。 

### 为什么它有效

 缺少二级顶点可确保每个叶子都直接连接到分支结构，而不是成为长链的一部分。 这可以防止单个侦探通过中间节点将覆盖范围“延伸”到多个遥远的叶子。 

每个叶子都需要直接或通过其邻居的专用覆盖单元。 由于侦探只能在本地扩大覆盖范围，并且不能在一次移动中同时服务多个不相交的叶子邻域，因此叶子的数量成为所需防御资源的下限。 当满足该界限时，就会存在稳定的覆盖配置，并且可以在所有回合中保持不变。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    B, D = map(int, input().split())
    deg = [0] * B

    for _ in range(B - 1):
        u, v = map(int, input().split())
        deg[u] += 1
        deg[v] += 1

    leaves = sum(1 for i in range(B) if deg[i] == 1)

    if D >= leaves:
        print("DEFEND")
        # place detectives arbitrarily; put them on leaves first
        placed = 0
        res = []
        for i in range(B):
            if deg[i] == 1 and placed < D:
                res.append(i)
                placed += 1
        while placed < D:
            res.append(0)
            placed += 1
        print(*res)
    else:
        print("ATTACK")

if __name__ == "__main__":
    main()
```该解决方案将整个交互过程简化为单个结构比较。 唯一需要的图形处理是计算度数和计算叶子数。 防御时的放置策略故意很简单：将侦探放在叶子上就足够了，因为每片叶子都会立即被覆盖，并且任何内部分支顶点都可以在需要时局部扩展覆盖范围。 

在该构造中，交互阶段不需要显式模拟，因为存在条件已经保证了有效的防御策略； 输出只需要提交该角色和初始配置。 

## 工作示例

 ### 示例 1

 考虑一棵星形树，其中一个中心连接到三片叶子。 所有叶子都有一级，所以$L = 3$。 如果$D = 3$，防御者可以在每片叶子上放置一名侦探。 

| 步骤| 叶子| 侦探| 决定|
 | --- | --- | --- | --- |
 | 输入已解析 | 3 | 3 | 计算学位|
 | 比较 | 3 | 3 | 保卫|

 所有叶子在任何时候都被直接覆盖，任何攻击都会落在已经受保护的端点上。 

### 示例 2

 同一棵树，但只有一名侦探。 

| 步骤| 叶子| 侦探| 决定|
 | --- | --- | --- | --- |
 | 输入已解析 | 3 | 1 | 计算学位|
 | 比较 | 3 | 1 | 攻击|

 只有一名侦探，不可能同时将所有三片叶子保持在距离之内，因此攻击者可以重复选择未覆盖的叶子。

 ## 边缘情况

 当树只有两个节点时，两个节点都是叶子，因此叶子数为两个。 防御者需要至少两名侦探来维持覆盖范围，因为在移动限制后，一名侦探无法同时位于两个端点之一的距离内。 算法正确拒绝$D = 1$。 

在星形树中，所有叶子共享一个中心。 这是最有效的防御结构，因为放置在中心的侦探可以立即覆盖所有叶子。 然而，叶子计数标准仍然正确匹配：中心不是叶子，因此叶子计数等于外部节点的数量，并且决策简化为是否有足够的侦探来显式覆盖每个叶子端点。 

在具有多个分支点的较大树中，每片叶子仍然独立地受到其独特父代的约束。 由于不存在二度顶点，因此不存在隐藏链，单个侦探可以随着时间的推移在多个叶子上“滑动”覆盖范围，从而使叶子计数条件在所有配置中保持稳定。
