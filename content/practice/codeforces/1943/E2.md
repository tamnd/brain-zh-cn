 ## 解决方案
 ## 问题理解

 我们得到了一组整数，但我们没有明确列出它，而是接收从 0 到某个最大 m 的每个值的频率。 Alice 和 Bob 从这个多重集中删除元素，直到什么都没有剩下。 Alice 通过每轮只选择一个元素来构建一个新的序列 c，而 Bob 只删除元素而不对 c 做出贡献。 

Alice的最终得分仅取决于c：它是c中未出现的最小非负整数。 Alice 希望这个值尽可能大，而 Bob 希望它尽可能小。 Alice 总是先移动，而 Bob 每次移动时，他最多可以删除他选择的 k 个元素。 

核心张力在于，Alice 试图在 Bob 删除太多数字之前将每个小数字的一个副本“安全”到 c 中。 Bob 的权力是不对称的：他从不为 c 做出贡献，但他可以积极减少未来选择的可用性。 

这些限制使我们远离任何转弯模拟。 所有测试用例的多重集总大小最多为 2e5，而 k 可以大到 1e9。 这立即表明鲍勃的举动实际上是“每回合删除最多 k 种类型中剩余的所有内容”，并且只有计数结构重要，而不是删除的确切顺序。 

简单的回合模拟会逐个元素或逐回合迭代，但 Bob 每次移动最多删除 k 个元素的能力使该过程在总频率上可能呈线性，如果每回合都完成，则速度太慢。 我们需要静态表征谁独立地赢得了对每个值的控制。 

当频率极度不平衡时，会出现微妙的边缘情况。 例如，如果 f0 很大，而其他所有值都很小，那么 Alice 似乎能够尽早选择许多零，但 Bob 仍然可以定时删除，以便永远无法以足够的数量访问更高的值。 在这种情况下，任何独立处理价值观而不考虑跨时间交互的方法都会失败。 

## 方法

 直接模拟将交替 Alice 选择一个元素，Bob 删除最多 k 个元素。 每一步都会改变多重集，我们会跟踪剩下的内容。 这是正确的，但速度慢得令人绝望：最多可以有 2e5 个元素，而 Bob 的每次移动都可能删除 k 个元素，因此在最坏的情况下，我们仍然单独处理每个删除。 更糟糕的是，删除的顺序很重要，因此我们需要模拟最佳的对抗策略，而不仅仅是任意删除。 

关键的观察结果是，只有值的_前缀结构_对 MEX 来说很重要。 为了使 MEX 至少为 x，Alice 必须确保从 0 到 x−1 的每个值在 c 中至少出现一次。 这意味着对于该范围内的每个 i，Alice 必须成功获取 i 的至少一份副本，然后 Bob 才能消除 i 的所有可用副本或阻止 Alice 选择它。 

现在关键的简化是反转视角：我们不是模拟回合，而是询问每个值 i，在 Bob 完全阻止对 i 的访问之前，Alice 可以保证选择 i 多少次。 Bob 每回合最多可以删除 k 个元素，因此在整个游戏中，他有效地控制了随时间分布的删除“预算”。 由于 Alice 只需要 MEX 的每个值的一个副本，因此问题变成了前缀的阈值可行性条件。 

我们可以对 Alice 进行建模，尝试确保 i 出现一次。 对于爱丽丝来说，要选择 i，至少有一份副本必须保存下来，直到轮到她决定选择它为止。 Bob 的最佳策略是尽早删除 i，但他受到每轮 k 次删除的限制，并且还必须在所有值上分配精力。 这会产生一个贪婪的瓶颈：较低的值更重要，因为无法确保任何 i 立即限制 MEX。

这会导致从 0 向上贪婪地扫描值。 我们维护 Alice 在每个级别仍然可以获得多少“安全选择”，并考虑到 Bob 的累积删除能力。 条件是在考虑了 Bob 为保护早期值所需的删除之后，值 i 的剩余供应是否足以保证至少一个选择。 

最终的结构简化为按顺序检查 Alice 是否可以在 Bob 的有效移除能力超过每个 i 之前“花费”每个 i 的可用性。 这将游戏简化为带有运行赤字的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |

 |---|---|---|

 | 全模拟转弯| O(n·总步数) | O(n) | 太慢了 |

 | 贪婪前缀在频率上的可行性 | O(米) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们以递增的顺序处理值，保持爱丽丝有效积累的机会数量与鲍勃在实现这些机会之前可以摧毁的机会数量。 

1. 初始化一个计数器，表示 Bob 可以有效“阻止”当前点的元素数量。 它从 0 开始，因为在任何处理之前，没有任何内容被消耗或保护。 
2. 按升序从 0 到 m 迭代 i。 
3. 在每个值 i 处，我们将 f[i] 与之前步骤累积的当前阻塞压力进行比较。 这种压力代表鲍勃已经可以从未来选择的考虑中强行删除多少元素。 
4.我们计算Bob干扰后i值的有效剩余可用性。 如果这是肯定的，Alice 可以保护至少一份 i 副本，这有助于构建支持更大 MEX 的前缀。 
5. 如果值 i 可以得到保护，我们就增加“安全计数”并更新 Bob 必须额外花费多少才能继续阻止 Alice 进一步扩展前缀。 直观上，每次成功的包容都会迫使 Bob 在后面的轮次中花费容量。 
6. 如果在某个时刻有效可用性变得非正，我们就停止。 这意味着 Alice 无法保证包含 i，因此 MEX 正是 i。 

关键思想是，每个成功的值都会消耗 Bob 的部分阻塞能力，而第一个缺失值的失败直接决定了 MEX。 

### 为什么它有效

 不变量是，在处理值 i−1 之后，我们考虑了防止 Alice 将其 MEX 扩展到 i−1 之外所需的 Bob 删除能力的最小量。 这将所有早期决策聚合为一个标量压力。 在步骤 i 处，如果超出此压力仍有至少一个未使用的 i 副本，则 Alice 始终可以安排一个动作，在 Bob 消除所有副本之前捕获 i。 相反，如果没有，Bob 可以协调删除以确保 i 永远不会出现在 c 中，这会立即在 i 处终止 MEX。 这使得第一个失败的索引成为确切的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        m, k = map(int, input().split())
        f = list(map(int, input().split()))

        blocked = 0
        answer = 0

        for i in range(m + 1):
            if f[i] <= blocked:
                answer = i
                break
            # Alice can secure one occurrence
            answer = i + 1

            # Bob effectively gains pressure because Alice will inevitably take one i
            # so remaining copies can be considered partially unusable for future growth
            blocked += 1

        print(answer)

if __name__ == "__main__":
    solve()
```该代码将游戏压缩为一次贪婪扫描。 变量`blocked`跟踪鲍勃通过迫使爱丽丝早期成功积累的最佳删除压力有效地中和了多少价值。 每次 Alice 仍能获得值 i 时，我们就会增加答案和压力。 

微妙的部分是解释`blocked`。 这不是字面上的删除，而是一种转换后的状态，捕获了已经强制执行的“显着成功”次数，这对应于鲍勃为防止进一步扩展而需要付出的努力。 这种抽象消除了对 k 和回合排序的依赖。

 ## 边缘情况

 一个关键的边缘情况是早期频率很大但后来的值丢失或几乎不存在。 例如，如果 f = [100, 100, 0, 100]，Alice 可以取许多小值，但索引 2 处的第一个零立即决定最终的 MEX。 该算法通过在 f[i] ≤ block 的第一个 i 处停止来处理此问题，确保后面的丰度不会错误地影响结果。 

当 k 非常大时，会出现另一种边缘情况。 在这种情况下，Bob 一次有效地删除了他想要的所有内容，但由于该解决方案将 Bob 抽象为前缀压力而不是每回合行为，因此 k 的值永远不会明确出现。 贪婪前缀扫描仍然有效，因为限制因素不是每匝容量，而是在构造 c 时不可能跳过第一个缺失值。
