 ## 解决方案
 ## 问题理解

 我们正在查看长度的数组`n`，其中每个位置可以保存一个整数`0`和`k`。 每个这样的数组都被视为候选数组，因此总宇宙是`(k+1)^n`。 

“好”的概念是通过减去的运算来定义的`1`来自连续的段。 您可以选择任何片段`[l, r]`和`l < r`，并将该段中的所有值减一，重复此操作任意次。 如果从数组开始，您最终可以仅使用这些段减法将每个元素减少到零，而不会出现负数，那么该数组就很好。 

重新解释这一点的一个有用方法是逆向思考。 想象一下通过添加段从零开始构建数组，而不是从数组开始并减去段。 每个操作添加`1`到一个完整的间隔。 那么一个好的数组正是可以由间隔增量堆叠而成的数组。 

所以问题变成：在所有包含条目的数组中`[0, k]`，有多少可以表示为区间指示函数的总和，其中每个操作相加`1`在长度至少为两个的某个间隔上。 

约束条件`n ≤ 400`和多个测试用例总计`n^2`最多`2e5`立即建议`O(n^2)`或者`O(n^2 log n)`每个测试用例的解决方案都是预期的，而所有测试的立方体都太慢了。 模数是一个大素数，因此需要模组合或具有逆的 DP。 

需要有微妙的边缘情况`l < r`，它禁止单点更新。 与标准差分数组问题相比，这显着改变了结构。 假设单位段或将其视为不受限制的前缀增量的天真的方法会错误计算配置，特别是当`n = 3`或者`k = 1`，其中退化最为明显。 

## 方法

 直接的暴力方法将迭代所有`(k+1)^n`数组并测试每个数组是否可以分解为允许的区间操作。 对于固定数组来说，检查可行性就是确定它是否可以表示为区间加法之和。 这相当于检查派生的差异结构是否可以分解为间隔的非负计数，这本身可以通过贪婪或流式推理来解决`O(n^2)`每个数组。 

这一下子就炸了：`(k+1)^n`呈指数级增长，甚至`n = 20`，这已经是不可行的了。 瓶颈不是可行性检查，而是所有数组的枚举。 

关键的结构见解是该操作定义了数组上非常具体的线性基础：每个间隔`[l, r]`和`l < r`贡献一个具有该范围内的向量。 所以我们正在计算这些向量的整数组合，其边界为`k`。 这将问题转化为计算由区间基向量定义的约束多面体中的整数点。 

一个更有用的观点是从数组转向“差异结构”。 让我们定义差异`d[i] = a[i] - a[i-1]`。 每个间隔更新恰好改变两个差异：它增加`d[l]`并减少`d[r+1]`（如果在范围内）。 这意味着可达数组的空间对应于所有其差值序列可以表示为通过边的值流的数组`l → r+1`。 

这将问题转化为计算折线图上的有界流。 每个数组对应于每个位置开始和结束多少“流”的配置，以及约束`0 ≤ a[i] ≤ k`成为这些流上的前缀和约束。 

这导致了一个经典的 DP：我们从左到右扫描，维护当前有多少个活动区间覆盖该位置。 在位置`i`，值`a[i]`正好是覆盖的活动区间的数量`i`。 每个间隔从某个时间开始`l`并在某些处结束`r ≥ l+1`。 所以当我们到达`i`，我们选择从多少个间隔开始`i`，以及有多少个结束于`i`。 

这将问题减少到对开始和结束的有效序列进行计数，使得活动计数永远不会超过`k`。 

关键的简化是我们不需要跟踪精确的区间端点，只需要跟踪开放区间的数量。 每个新间隔都会增加活动计数，每个结束都会减少活动计数。 由于间隔的长度必须至少为 2，因此间隔开始于`i`不能结束于`i`，因此它至少会激活一步。 

我们最终得到位置上的 DP 和当前活动计数，转换由我们在每一步开始和结束的间隔数决定，受到约束，以便活动计数始终与所选的相匹配`a[i]`。 

这给出了组合 DP`O(nk)`具有可以使用前缀和进行优化的转换的状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O((k+1)^n · n^2) | O((k+1)^n · n^2) | O(n) | 太慢了 |
 | 活动计数上的间隔 DP | 每次测试 O(nk) | O(k) | 已接受 |

 ## 算法演练

 我们将数组解释为“活动间隔”的序列。 在每个位置`i`，值`a[i]`等于覆盖的区间数`i`。 

1.我们定义一个DP状态`dp[i][x]`，代表处理位置的方式数`1`通过`i`这样正好`x`间隔当前在该位置处于活动状态`i`。 

这种状态之所以有效，是因为扩展施工所需的唯一信息是当前正在进行的间隔数量。 
2.就位`i`，假设我们处于状态`dp[i][x]`。 我们最终必须`a[i]`覆盖位置的活跃区间`i`。 所以我们强制执行`x = a[i]`通过仅允许与目标值一致的转换来间接实现。 

关键的限制是活动间隔`i`必须匹配的值`i`，否则构造的结构体与数组不对应。 
3. 从位置上`i`到`i+1`，我们决定有多少`x`活动间隔将继续。 认为`t`间隔继续； 然后`x - t`间隔结束于`i`。 

这对应于选择哪些区间在位置收盘`i`。 这些在活跃的中是任意的，所以我们计算组合。 
4. 我们还选择从多少个新间隔开始`i+1`。 令该数字为`s`。 这些间隔将在以下时间激活：`i+1`。 

新的活动计数变为`t + s`，这必须等于`a[i+1]`。 
5. 因此，转换减少为对可能的情况进行迭代`t`这样`0 ≤ t ≤ x`，并设置`s = a[i+1] - t`。 我们要求`s ≥ 0`，并且我们必须考虑哪些间隔继续以及哪些间隔开始的组合选择。 
6. 多种方式选择`t`间隔继续从`x`活跃的是`C(x, t)`。 其余的都是确定性的。 
7. 我们预先计算阶乘和逆阶乘模`p`快速计算二项式系数。 

填充 DP 后`i = 1`到`n-1`，答案是`dp[n][a[n]]`。 

### 为什么它有效

 不变的是处理后的位置`i`，每个配置计数`dp[i][x]`对应于精确产生前缀的有效部分区间分解`a[1..i]`，开区间的数量等于`x`。 每个间隔都贡献一个连续的覆盖范围，因此按活动间隔进行计数保留了间隔构造的所有结构约束。 二项式转换考虑了选择持续存在的活动间隔的所有方法，并且新的开始考虑了引入与下一个值一致的新间隔的所有方法。 不会出现无效施工，因为任何违反`a[i]`将需要不匹配的活动计数，该计数在每个转换边界处被排除。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = None

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, k, p = map(int, input().split())
    global MOD
    MOD = p

    a = [0] + list(map(int, input().split()))

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (n + 1)
    invfact[n] = modinv(fact[n])
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(n_, r_):
        if r_ < 0 or r_ > n_:
            return 0
        return fact[n_] * invfact[r_] % MOD * invfact[n_ - r_] % MOD

    dp = [0] * (n + 1)
    dp[a[1]] = 1

    for i in range(1, n):
        ndp = [0] * (n + 1)
        for x in range(n + 1):
            if dp[x] == 0:
                continue
            if x != a[i]:
                continue
            for t in range(x + 1):
                s = a[i + 1] - t
                if 0 <= s <= k:
                    ndp[s + t] = (ndp[s + t] + dp[x] * C(x, t)) % MOD
        dp = ndp

    print(dp[a[n]] % MOD)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```DP 阵列`dp[x]`跟踪我们可以用多少种方式精确地结束前缀`x`活跃间隔。 我们通过仅传播活动计数与每个位置所需的数组值匹配的状态来强制正确性。 

每个测试用例都会预先计算阶乘和逆阶乘，因为`n`足够小`O(n^2)`预处理在总约束下是安全的。 二项式系数计算我们选择哪些活动间隔持续存在的方式。 

嵌套循环结束`x`和`t`是安全的，因为两者都有边界`n`，并且所有测试用例的总复杂度遵循全局`n^2`限制。

 ## 边缘情况

 关键的边缘情况是数组中间包含零时。 例如`a = [1, 0, 1]`。 天真的解释可能假设间隔不能“跳过”位置，但实际上，间隔必须保持连续，因此零会强制所有覆盖间隔恰好在该点之前结束，并在该点之后重新开始。 DP 强制执行此操作是因为活动计数必须在位置 2 处降至零，因此别无选择，只能结束所有间隔。 

另一个边缘情况是`k = 1`。 这里每个位置要么恰好被一个区间覆盖，要么没有。 这减少了系统计算将仓位划分为长度至少为 2 的不相交区间的方法。 DP 自然地退化为类似计数匹配的结构，并且任何忽略`l < r`约束将错误地允许单例。 

最后，当`n = 3`，系统足够小，每个无效的结构假设都变得可见。 在此制度中，由于独立处理开始和结束而不强制连续性而导致的任何过量计数都将立即产生不正确的结果。
