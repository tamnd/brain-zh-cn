 ## 解决方案
 # 问题理解

 The task is about maintaining whether a sorted sequence has enough empty integer positions to insert exactly`k`新的价值观。 原始数组应该是严格递增的，但每次更新后，一个元素可能会发生变化，因此数组可能会暂时失效。 每次更新后我们必须决定是否仍然可以插入。 

考虑两个相邻值`a[i]`和`a[i+1]`。 它们之间的任何插入值必须是严格大于的整数`a[i]`并且严格小于`a[i+1]`。 该间隙中的可用位置数量为：`a[i+1] - a[i] - 1`例如，之间`5`和`10`，可能的插入值为`6, 7, 8, 9`，所以这个间隙有助于`4`职位。 

我们可以插入的值的总数是所有间隙大小的总和。 答案是`YES`恰好当每个相邻对都在增加并且总容量至少为`k`。 

这些限制迫使我们无法在每次更新后重建整个数组。 数组长度和更新次数各能达到`2 * 10^5`。 几秒钟的时间里，`O(nq)`解决方案将执行大约`4 * 10^10`操作，这远远超出了可能的范围。 我们需要使每次更新仅影响恒定数量的值。 

在某些情况下，简单的解决方案很容易被破坏。 

如果更新使两个相邻值相等，则数组不再严格递增，并且任何插入都无法修复原始顺序。 

对于输入：```
n = 3, k = 1
a = [1, 3, 5]
update: a[2] = 1
```数组变成`[1, 1, 5]`。 正确的输出是：```
NO
```仅检查空闲位置数量的解决方案会错误地计算之间的差距`1`和`5`并可能会回答`YES`。 

另一种边缘情况是，即使数组本身仍然有效，所有间隙都太小。 

对于输入：```
n = 4, k = 5
a = [1, 2, 3, 4]
```每个间隙的大小为零，因此正确的输出是：```
NO
```该数组已经是严格递增的，但是没有可以插入的整数。 

The last important case is`k = 0`。 不需要额外的数字，因此任何严格递增的数组都是可以接受的。 

对于输入：```
n = 3, k = 0
a = [10, 20, 30]
```正确的输出是：```
YES
```该算法不得意外地需要至少一个可用间隙。 

# 方法

 直接方法将模拟插入过程。 我们可以检查每个可能的间隙，计算有多少个整数适合其中，并在每次更新后添加这些计数。 这是正确的，因为唯一重要的是相邻元素之间未使用的整数位置的总数。 但是，在一次更新后，扫描所有`n - 1`差距成本`O(n)`。 和`q`更新，最坏的情况变成`O(nq)`，这太慢了。 为了`n = q = 2 * 10^5`，这大约是四百亿间隙检查。 

关键的观察结果是点更新仅更改接触修改位置的间隙。 如果`a[i]`改变，仅对`(i-1, i)`和`(i, i+1)`可以有不同的间隙尺寸。 其他每一对都保持完全相同。 这将问题转化为维护两条信息：每个相邻对是否有效，以及所有间隙容量的总和。 

我们可以存储无效相邻对的数量。 我们还可以将总容量存储为`a[i+1] - a[i] - 1`在所有看起来有效的相邻对上。 当值发生变化时，我们会删除受影响间隙的旧贡献并添加新的贡献。 芬威克树或线段树是不必要的，因为我们只需要全局总和，而不是范围查询。 一个简单的运行总计就足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(1) | O(1) | 太慢了|
 | 最佳| O(n) 预处理后的 O(q) | O(n) | 已接受 |

 # 算法演练

 1. 读取初始数组并计算每个相邻对的贡献。 对于每一对，检查左侧值是否小于右侧值。 如果不是，请增加无效对的数量。 否则，将可用间隙大小添加到总容量中。 
2. 在处理索引更新之前`i`，从两个可能受影响的间隙中删除旧信息：之前的间隙`i`以及之后的差距`i`。 这是旧值参与答案的唯一地方。 
3. 更换`a[i]`与新的价值。 
4. 为相同的两个受影响的间隙添加新信息。 如果新的相邻对无效，则增加无效计数器。 否则，添加新的可用位置数。 
5.更新后，打印`YES`如果没有无效的相邻对并且总容量至少为`k`。 否则打印`NO`。 

为什么这样做：插入值后的最终数组必须按排序顺序保留原始值。 如果任何相邻的原始值没有增加，则任何插入的值都无法解决该矛盾。 如果所有相邻对都有效，则每个可用整数位置恰好属于一个间隙，因此间隙大小的总和恰好是可以插入的最大值数。 条件`capacity >= k`既是必要的又是充分的。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, k, q = map(int, input().split())
        a = list(map(int, input().split()))

        bad = 0
        space = 0

        def add_gap(i, sign):
            nonlocal bad, space
            if i < 0 or i + 1 >= n:
                return
            if a[i] >= a[i + 1]:
                bad += sign
            else:
                space += sign * (a[i + 1] - a[i] - 1)

        for i in range(n - 1):
            add_gap(i, 1)

        for _ in range(q):
            i, x = map(int, input().split())
            i -= 1

            add_gap(i - 1, -1)
            add_gap(i, -1)

            a[i] = x

            add_gap(i - 1, 1)
            add_gap(i, 1)

            if bad == 0 and space >= k:
                ans.append("YES")
            else:
                ans.append("NO")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```辅助函数`add_gap`保持一对相邻对的贡献。 这`sign`参数决定我们是添加当前贡献还是在更新之前删除旧贡献。 

初始化循环处理每个间隙一次。 更新期间，代码仅涉及索引`i - 1`和`i`，因为这些是包含更改元素的唯一间隙。 内部边界检查`add_gap`处理对第一个或最后一个元素的更新，而不会创建无效的数组访问。 

计数器存储为整数，可以大致达到`10^14`，因为数组值可以大到`10^9`并且可能存在很多差距。 Python 整数会自动处理此问题，而在具有固定大小整数的语言中则需要 64 位类型。

 # 边缘情况

 对于无效订单的情况：```
3 1 1
1 3 5
2 1
```更新后，数组变为`[1,1,5]`。 该算法消除了索引周围的旧间隙`1`，插入新的间隙，并发现第一对无效。 无效计数器变为`1`，所以结果是`NO`。 

对于没有可用插槽的情况：```
4 5 0
1 2 3 4
```该数组是严格递增的，但每个差值都是一。 每个差距都有贡献`0`，所以总容量为`0`。 自从`0 < 5`，算法返回`NO`。 

对于零所需的插入：```
3 0 1
10 20 30
```总容量并不重要，因为`k`为零。 唯一的要求是没有无效的对。 由于数组严格递增，因此算法返回`YES`。
