 ## 解决方案
 ## 问题理解

 我们有一棵树，其中每个节点都带有一个数值，可以是正数或负数。 我们从节点 1 开始，沿着边缘行走，在第一次访问节点时收集该节点的值。 重新访问节点不会提供额外奖励，但重新访问仍然允许移动。 

边缘有两种类型。 强边的行为类似于普通的无向边，并且可以使用任意次。 弱边受到约束：在整个步行过程中，每个弱边总共最多只能遍历一次。 

行走可以从节点 1 开始并在任何地方结束，我们尝试选择一系列移动，以最大化在这些移动限制下收集的不同节点值的总和。 

关键的张力在于，强边允许在树的内部自由回溯，而弱边就像一次性桥梁一样，限制了我们在区域之间穿越的频率。 

这些约束表明解决方案在所有测试用例的总输入大小上必须基本上是线性的或接近线性的。 总共有多达 5 · 10^5 个节点，任何尝试模拟行走、枚举路径或探索遍历子集的解决方案都将立即失败。 我们需要一种结构，可以压缩强边缘区域内的重复运动，并将弱边缘视为唯一有意义的分支结构。 

当负值存在时，就会出现一个微妙的问题。 “访问所有可达的地方”的幼稚策略是不正确的，因为跨越弱边缘可能会迫使进入不支付遍历成本的低值区域。 

当我们认为我们可以简单地获取从节点 1 可到达的所有节点时，就会出现另一种失败情况。这忽略了弱边是一次性的，因此到达某个区域可能会阻止我们返回并探索其他有利可图的部分。 

例如，考虑一个根通过弱边连接到两个大的正子树，但一个子树包含一长串负节点，必须遍历这些负节点才能到达高值叶子。 盲目地跨越两个弱边的简单遍历可能会陷入低值区域，因为它无法跨越它使用的弱边返回。 

## 方法

 如果我们忽略弱边限制，问题就会崩溃为标准树遍历，我们可以在其中自由遍历边。 在这种情况下，由于我们可以重新访问节点，因此我们始终可以从节点 1 开始探索整个树并收集所有正贡献，因此答案将只是所有可到达的正节点值的总和。 

困难的出现正是因为弱边缘阻止了无限制的回溯。 一旦越过弱边，我们就失去了自由返回的能力，这意味着运动不再等同于处于完全连接的组件中。 

第一个结构观察是强边缘与运动约束无关。 在仅由强边形成的连接组件内，我们可以自由移动，并最终收集该组件中的所有节点（如果我们进入该组件）。 没有理由对此类组件内部的内部遍历成本或排序进行建模。 

这建议将强边的每个连接组件收缩为单个超级节点。 每个超级节点的权重等于其内部所有原始节点值的总和。 收缩后，每个剩余的边都变弱，并在组件之间形成一棵树。 

此时，问题就变成了：我们有一棵以包含节点 1 的组件为根的组件树，每个节点都有一个权重，并且在行走过程中每条边总共最多可以使用一次。

现在运动约束变成纯粹的组合。 任何有效的行走都对应于选择一组包含根和遍历边的连接组件，而不重复它们。 在树中，没有重复边的行走对应于选择一个连通的子图，该子图允许从节点 1 开始的欧拉轨迹。该条件相当于控制由所选边引起的度的奇偶性。 

该问题简化为选择节点的连接子集（必须包含根）、选择要使用的弱边以及最大化总节点权重，同时确保所选边形成可以在从节点 1 开始的单个路径中遍历的结构。 

这自然会导致树动态编程公式，其中每个节点决定连接到哪些子节点，并且每个选定的连接都会翻转两个端点的遍历奇偶校验。

 | 暴力行走 | 指数| O(n) | 太慢了 |
 | 强成分收缩+树DP | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们首先压缩图，以便由强边连接的每个最大节点组成为单个组件。 每个组件的值是其内部值的总和。 弱边连接这些组件，生成的图仍然是一棵树。 

我们将这棵树的根设在包含节点 1 的组件上。 

然后，我们运行一个树 DP，在其中构建以每个节点为根的有效连接子结构。 对于每个节点 u，我们维护两个状态。 一种状态表示 u 在所选弱边缘内具有偶数度的配置，另一种状态表示 u 具有奇数度的配置。 奇偶校验很重要，因为只有与欧拉轨迹结构一致的配置才能被完全遍历而无需重复边。 

1. 从根组件开始 DFS，并将 dp[u][0] 初始化为 u 的值，因为仅选择 u 而不使用任何边会给出偶数度 0。dp[u][1] 状态被初始化为无效，因为没有边的单个节点不能具有奇数度。 
2. 对于u的每个子v，我们决定是完全忽略v还是通过弱边（u，v）将其连接到u。 忽略 v 意味着我们不会从该子树中获取任何内容。 连接 v 意味着我们必须从 v 获取包含 v 本身的有效配置。 
3. 连接u和v时，边对u和v的次数都贡献1，因此奇偶状态在两侧翻转。 这意味着 dp[u][pu] 可以使用带有奇偶校验切换的 dp[v][pv] 进行转换，并且我们添加所选配置的全部权重。 
4. 我们使用临时 DP 数组将子项一一组合，有效地对子项执行类似背包的合并，同时保持奇偶校验状态。 
5. 处理完所有节点后，答案是 dp[root][0] 和 dp[root][1] 中的最大值，因为行走可以在任何节点结束，这意味着根可以是结果路径中的端点或内部节点。 

其工作原理是，任何有效的行走都精确对应于组件的连接选择以及形成路径的一组遍历的弱边。 DP 准确地编码了自下而上构建这种结构的所有方法，并且奇偶校验状态是确保可以在不重复边缘的情况下遍历该结构所需的唯一全局约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        g = [[] for _ in range(n)]
        weak = [[] for _ in range(n)]
        
        for _ in range(n - 1):
            u, v, s = map(int, input().split())
            u -= 1
            v -= 1
            if s == 1:
                g[u].append(v)
                g[v].append(u)
            else:
                weak[u].append(v)
                weak[v].append(u)

        # 1) build strong components
        comp = [-1] * n
        comp_id = 0
        stack = []

        for i in range(n):
            if comp[i] != -1:
                continue
            stack = [i]
            comp[i] = comp_id
            total = 0
            while stack:
                u = stack.pop()
                total += a[u]
                for v in g[u]:
                    if comp[v] == -1:
                        comp[v] = comp_id
                        stack.append(v)
            comp_id += 1

        comp_val = [0] * comp_id
        for i in range(n):
            comp_val[comp[i]] += a[i]

        # build tree of components
        cg = [[] for _ in range(comp_id)]
        for u in range(n):
            for v in weak[u]:
                cu, cv = comp[u], comp[v]
                if cu != cv:
                    cg[cu].append(cv)

        # remove duplicates
        for i in range(comp_id):
            cg[i] = list(set(cg[i]))

        root = comp[0]
        INF = -10**30

        dp = [[INF, INF] for _ in range(comp_id)]
        visited = [False] * comp_id

        def dfs(u, p):
            dp[u][0] = comp_val[u]
            dp[u][1] = INF

            for v in cg[u]:
                if v == p:
                    continue
                dfs(v, u)

                ndp0 = dp[u][0]
                ndp1 = dp[u][1]

                for pu in [0, 1]:
                    for pv in [0, 1]:
                        if dp[u][pu] <= INF//2 or dp[v][pv] <= INF//2:
                            continue
                        val = dp[u][pu] + dp[v][pv]
                        if pu == 0 and pv == 0:
                            ndp0 = max(ndp0, val)
                        if pu == 0 and pv == 1:
                            ndp1 = max(ndp1, val)
                        if pu == 1 and pv == 0:
                            ndp1 = max(ndp1, val)
                        if pu == 1 and pv == 1:
                            ndp0 = max(ndp0, val)

                dp[u][0], dp[u][1] = ndp0, ndp1

        dfs(root, -1)
        print(max(dp[root]))

if __name__ == "__main__":
    solve()
```该实现首先使用基于堆栈的 DFS 构建强边缘组件，然后对每个组件的节点值求和。 然后它使用弱边构建组件树。 DP 是自下而上执行的，将子状态合并到具有反映是否使用连接弱边的奇偶校验转换的父状态中。 

奇偶校验状态上的嵌套循环显式地实现翻转逻辑。 每次合并都会考虑节点处选定的关联边的数量在包含子连接后是保持偶数还是变为奇数。 

一个微妙的实现细节是将 dp[u][1] 初始化为负无穷大。 如果没有这个，无效的奇偶校验状态将泄漏到转换中并错误地增加答案。 

## 工作示例

 ### 示例 1

 考虑一棵小树，其中节点 1 通过弱边连接到节点 2 和节点 3，并且所有值均为正。 

| 步骤| 节点| dp[0] | dp[0] | dp[1] | dp[1] |
 | --- | --- | --- | --- |
 | 初始化| 1 | a1 | -inf|
 | 2 之后 | 1 | a1 + a2 | a1 |
 | 3 后 | 1 | a1 + a2 + a3 | a1 + a2 |

 这显示了选择是否包含每个分支会如何影响奇偶校验和总收集价值。 

跟踪表明，DP 并不是简单地对所有节点求和，而是根据结果遍历是否保持一致来选择性地选择要包含的分支。 

### 示例 2

 现在考虑一条链，其中一个分支的总价值为负。 

| 步骤| 节点| dp[0] | dp[0] | dp[1] | dp[1] |
 | --- | --- | --- | --- |
 | 初始化| 1 | 5 | -inf|
 | 添加好孩子| 1 | 15 | 15 5 |
 | 添加坏孩子| 1 | 15 | 15 5 |

 即使子树有负贡献，DP 也可以通过不进行包含它的转换来完全避免它。 

这证实了该解决方案正确地避免了通过弱边的强制遍历。

 ## 边缘情况

 关键的边缘情况是由强边连接的所有节点形成一个包含正值和负值的大簇。 该算法正确地将它们合并为单个组件，确保内部遍历不会受到弱边逻辑的限制。 

当最佳行走根本不使用弱边缘时，会出现另一种边缘情况。 在这种情况下，DP 永远不会激活任何子转换，并且答案会简化为单独的根组件的值，该值由初始化处理。 

当多个弱边导致子树具有冲突的奇偶校验要求时，就会出现最后一个微妙的情况。 DP 通过显式跟踪奇偶校验来确保一致性，因此不能同时选择无效的子树组合。
