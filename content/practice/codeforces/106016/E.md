 ## 解决方案
 ## 问题理解

 给定两个长度相等的字符串，并且允许我们最多使用一次操作来修改第一个字符串。 该操作选择一个连续的段并将其反转。 在不执行任何操作或仅执行一次此类反转之后，我们将结果字符串与按字典顺序排列的第二个字符串进行比较。 任务是确定我们是否可以使第一个字符串严格小于第二个字符串。 

词典比较的行为类似于词典顺序：我们从左到右扫描，字符不同的第一个位置决定结果。 

所有字符串长度之和最多为 100000 的约束立即排除了尝试所有可能反转间隔的任何解决方案。 有 O(n²) 间隔，即使每个间隔进行线性检查也已经超出限制。 这将我们推向贪婪或基于前缀的决策过程，其中每个测试用例都在线性时间内处理。 

一个微妙的点是该操作可能会使字符串的某些部分变得更糟。 扭转一个细分市场并不会“局部改善”； 它重新排列了一个块，因此必须通过字典顺序全局推理效果，而不是仅通过局部比较。 

一种重要的边缘情况是字符串已经相等。 即使如此，反转也可能会使第一个字符串变小。 例如，如果我们有一个像这样的字符串`ba`, 逆向给出`ab`，小于`ba`即使我们在假设的意义上开始等于目标。 仅检查第一个不匹配已存在的情况的简单解决方案将在这里失败。 

另一种边缘情况是不使用反转时。 如果原始字符串按字典顺序已经较小，那么答案立即是肯定的。 

## 方法

 暴力方法很简单：尝试每对索引 l 和 r，反转该段，并将结果字符串与目标字符串进行比较。 每次反转的成本为 O(n)，并且有 O(n²) 个段选择，因此每个测试用例的总复杂度变为 O(n³)。 即使使用滚动哈希将比较成本降低到 O(1) 也不能修复候选者的基本 O(n²) 数量，因此这仍然太慢。 

关键的观察是，字典顺序是由我们可以强制改进的第一个位置决定的。 一旦我们确定了位置 i，i 之前的所有内容都必须与原始字符串保持相同（因为之前的任何更改都会主导比较）。 因此，如果反转有用的话，应该选择影响需要改进的最早可能的位置。 

这将问题简化为决定，对于每个前缀位置 i，我们是否可以使用不干扰较早字符的反转将小于 b[i] 中相应字符的字符带到位置 i。 

在段反转中，使角色向前移动的唯一方法是将其选择为段的右端点。 因此，对于每个位置 i，我们想知道是否存在某个 j ≥ i，使得反转 a[i..j] 将 a[j] 放置在位置 i，并且该字符足够小以改善字典顺序。 

这导致为每个后缀保留可用的最小字符，因为这是我们可能继续前进的最佳候选字符。

 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(n) | 太慢了 |
 | 最优贪心 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1、首先检查原字符串a按字典顺序是否已经小于b。 如果是，我们可以立即回答“是”，因为该操作是可选的。 
2. 预先计算一个结构，让我们知道对于每个位置 i，a[i..n−1] 中的最小字符是什么。 我们还跟踪这个最小字符出现的一个索引，最好是最右边的出现，以便我们在形成反转段时具有最大的灵活性。 
3. 从左到右扫描位置。 在位置 i 处，我们假设所有先前的位置都与 b 完全匹配，因为否则字典顺序比较早就已经决定了。 
4. 在每个位置 i，我们将可以带到位置 i 的最佳可能字符（即从 i 开始的后缀中的最小字符）与 b[i] 进行比较。 
5. 如果这个最小后缀字符严格小于b[i]，并且其出现索引j至少为i，那么我们可以选择l = i且r = j。 反转该段会将 a[j] 带到位置 i，同时保持较早的位置不变。 这保证了与 b 的第一次不匹配发生在 i 处并且是有利的，因此我们可以立即回答“是”。 
6. 如果最小后缀字符等于 b[i]，那么即使是最好的可能移动也无法改善位置 i，因此我们继续下一个索引。 
7. 如果我们完成扫描后没有找到有效的位置i，则答案是否定的。 

正确性依赖于这样一个事实：词典编排改进必须发生在可以强制执行差异的最早位置。 任何跳过第一个可改进索引并修复后一个索引的尝试都将受到早期等式约束的支配，因为早期位置仍会匹配 b 并阻止后来的优势发挥作用。 

### 为什么它有效

在任何索引 i 处，如果我们决定位置 0 到 i−1 必须保持等于 b，那么获胜的唯一方法就是强制 a[i] < b[i]。 反转操作只能将后缀中的一个字符移至位置 i，并且最好的此类字符是该后缀中的最小值。 如果即使该字符不小于 b[i]，那么从 i 处或之后开始的任何反转都无法改善位置 i 处的字典顺序，并且延迟决策只会使情况变得更糟，因为较早的位置保持固定。 这创建了一个单调的决策结构，其中第一个可行的改进始终是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input().strip())
        a = input().strip()
        b = input().strip()

        # If already smaller, no need to use operation
        if a < b:
            print("Yes")
            continue

        # suffix minimum character and position
        n = len(a)
        suf_min = [''] * n
        suf_pos = [0] * n

        suf_min[-1] = a[-1]
        suf_pos[-1] = n - 1

        for i in range(n - 2, -1, -1):
            if a[i] < suf_min[i + 1]:
                suf_min[i] = a[i]
                suf_pos[i] = i
            else:
                suf_min[i] = suf_min[i + 1]
                suf_pos[i] = suf_pos[i + 1]

        ok = False

        for i in range(n):
            if suf_min[i] < b[i]:
                j = suf_pos[i]
                if j >= i:
                    ok = True
                    break
            if a[i] != b[i]:
                break

        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```该代码首先检查不需要操作的简单情况。 然后，它构建后缀最小值，以便对于每个位置，我们可以立即知道可以通过从那里开始的逆转向前拉动的最佳角色。 扫描强制我们只考虑前缀仍然与目标字符串匹配的位置，因为否则词典比较就已经发散了。 

关键的实现细节是存储最小字符和它出现的索引。 如果没有索引，我们会知道要向前移动哪个字符，但不知道它是否可以使用有效的反转实际移动到位置 i 。

 ### 示例 1

 b =“出租车”

 我们计算后缀最小值：

 | 我| 一个[我] | 后缀最小| 位置|

 当 i = 0 时，后缀 min 为`a`， 和`a < b[0] = c`，所以我们可以反转 [0,2]，产生`"acb"`，小于`"cab"`。 

该轨迹显示了单个反转如何将全局最小的字符向前拉到最早的决策点。 

### 示例 2

 输入：

 一个=“abc”

 b =“abc”

 后缀最小值：

 | 我| 一个[我] | 后缀最小| 位置|
 | --- | --- | --- | --- |
 | 0 | 一个 | 一个 | 0 |
 | 1 | 乙| 乙| 1 |
 | 2 | c | c | 2 |

 没有任何位置的后缀最小值严格小于 b[i]。 如果不先打破平等，任何逆转都不可能在任何位置上带来严格的改进，所以答案是否定的。 

这表明，即使字符串相等，该结构也能正确防止误报。

 ## 边缘情况

 当字符串已经相等时，算法仍然正确地尝试找到可以将后缀字符向前移动以创建严格减少的位置。 如果不存在这样的位置，则扫描永远不会触发成功，并且答案仍然是“否”。例如，`a = "abc"`和`b = "abc"`，每个后缀最小值都与相应的字符匹配，因此任何反转都不能在任何位置产生严格的优势。 

当第一个字符已经较小时，例如`a = "a..."`和`b = "b..."`，算法在 i = 0 时立即检测到成功，无需考虑更深层次的结构。 位置 0 处的后缀最小值最多为`a[0]`，这已经足以满足条件了。 

当改进仅存在于字符串深处时，扫描可确保较早的位置正确阻止它。 如果在任何可行的改进之前发生不匹配，则循环会提前中断，通过尊重字典优先级来保持正确性。
