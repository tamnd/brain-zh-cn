 ## 解决方案
 ## 问题理解

 给出一排孩子，每个孩子都有一个等级。 我们必须为每个孩子分配正数的cookie，但分配不能是任意的。 唯一的结构要求是本地的：每当一个孩子的评分严格高于其前一个孩子时，该孩子必须收到比其左邻居更多的 cookie。 

相反方向没有约束。 如果评分下降、保持不变或以任何非增加的方式跳跃，只要每个孩子至少有一个，饼干的数量就可以做任何事。 

任务是最小化所有子项的 cookie 总数，同时尊重这些本地比较。 

输入大小很小：最多 100 个测试用例，每个测试用例最多有 100 个子级。 即使二次或三次方法也是可以接受的，但条件的结构表明线性构造是可能的。 

当人们试图在两个方向上强制执行约束或尝试在初始分配后全局重新平衡计数时，就会出现天真的错误。 例如，考虑评级`[1, 3, 2]`。 粗心的对称规则可能会给出`[1, 2, 1]`，它失败了，因为第二个孩子必须严格超过第一个。 另一种失败模式是仅在完整通过后检测到违规时才尝试进行调整，这可能会反复向后级联更改。 

关键的困难在于约束仅从左到右向前传播，而不是向后传播，这使得局部决策一旦做出就成为最终决定。 

## 方法

 暴力解释是将每个孩子的 cookie 数量视为受不等式约束的变量：每个孩子至少有一个 cookie，并且对于评分增加的每个位置，我们在相邻变量之间施加严格的不等式。 人们可以尝试搜索所有有效的分配或反复放松约束直到收敛。 

这种方法很快就变得不可行，因为可能的 cookie 分布的数量随着 n 呈指数增长。 即使我们将值限制在合理的范围内，重复修复违规行为也可能需要多次传递，并且在最坏的情况下，每次调整都会在整个数组中传播多次，从而导致每个测试用例出现二次或更差的行为。 

约束的结构比最初出现的要简单。 每个限制仅将孩子与其左近邻居进行比较。 不存在全局耦合。 这意味着一旦我们知道前一个位置的值，我们就可以贪婪地确定每个位置的最小有效值。 

关键的观察是，我们被迫增加 cookie 的唯一时间是当评级严格增加时。 如果评级没有增加，我们可以随意重置为最小可能值，即 1。这消除了向后修正或全局优化的任何需要。 

我们最终得到一次从左到右的传递，其中每个位置仅由前一个位置决定。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 将第一个孩子的答案初始化为 1。这是强制的，因为每个孩子必须至少有一个 cookie，并且没有左邻居约束。 
2. 从第二个孩子到最后一个孩子遍历数组。 在每个位置 i，将当前评级与先前评级进行比较。 
3. 如果当前评分大于先前评分，则指定 cookies[i] = cookies[i−1] + 1。这是满足严格不等式同时保持总和最小的最小值。 任何较小的值都会违反规则。 
4. 否则，指定 cookies[i] = 1。由于没有要求评级不增加，因此选择尽可能小的值可以使总和保持最小。 
5. 如果需要内存优化，则在计算时累加所有分配值的总和，而不是存储整个数组。 

### 为什么它有效

 在每个位置，分配仅取决于前一个位置和本地评级比较。 一旦 cookies[i−1] 被固定，最小的有效 cookies[i] 就完全确定了：要么是 1，要么 cookies[i−1] + 1（如果约束触发）。 任何进一步减少 cookies[i] 的尝试都会立即违反涉及索引 i 的唯一约束。 由于未来没有约束可以迫使相对于早期位置的减少，因此这些局部最小值组合成全局最小解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        r = list(map(int, input().split()))

        cookies = 1
        prev = 1
        total = 1

        for i in range(1, n):
            if r[i] > r[i - 1]:
                prev = prev + 1
            else:
                prev = 1
            total += prev

        out.append(str(total))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现仅保留先前的 cookie 值，而不是存储整个数组。 这已经足够了，因为每个步骤仅取决于前一个步骤。 变量`prev`代表当前孩子分配的cookie，根据评分比较进行更新。 

积累成`total`避免在最后重建数组。 这直接符合贪心逻辑。

 ## 边缘情况

 对于单个子项，算法会立即分配一个 cookie，因为没有前任项可供比较。 规则集没有施加进一步的约束，因此输出保持为 1。 

对于严格递增的序列，例如`[1, 2, 3, 4]`，算法不断递增`prev`，生产`[1, 2, 3, 4]`。 这证实了链式增加可以正确传播，而不需要任何向后调整。 

对于严格递减序列，例如`[5, 4, 3, 2]`，每次比较都不满足条件，所以`prev`每一步都重置为 1。 结果变成`[1, 1, 1, 1]`，这是最小的，因为没有约束强制任何增加。
