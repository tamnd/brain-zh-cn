 ## 解决方案
 ## 问题理解

 我们有一个固定的数字$x$和一长串值$a_i$。 对于每个$a_i$，我们想要找到最小的正整数$z$满足两个条件：它必须除$x$，并且它必须无法划分$a_i$。 如果每个除数$x$也分$a_i$，那么就没有这样的$z$存在，答案是$-1$。 

读取任务的另一种方法是对于每个查询值$a_i$，我们扫描所有因数$x$按升序排列，并询问除数集之间第一个“不匹配”发生在哪里$x$和$a_i$。 

这些限制使得结构变得重要。 数组大小可达一百万，值可达$10^{12}$。 这立即排除了任何试图独立分解每个数字或重新计算除数的方法$x$每个查询重复一次。 即使每个查询对大除数集进行线性扫描也变得至关重要，因为数字的除数计数高达$10^{12}$病理情况下仍可达100万左右。 

出现微妙的失败情况时$a_i$可以被每个约数整除$x$。 例如，如果$x = 12$，它的约数是$1,2,3,4,6,12$。 如果$a_i = 60$，其中每一个都除以 60，所以答案一定是$-1$。 提前停止或假设缺失除数始终存在的天真的方法会错误地返回 1 或另一个小值。 

当最小除数时会发生另一种边缘情况$x$始终为 1，已经不符合条件。 这是不可能的，因为 1 可以整除所有内容，因此扫描始终以“有效”除数开始。 第一个有意义的失败必须发生在某个大于 1 的除数处。 

## 方法

 直接的解决方案立即出现。 我们可以枚举所有的约数$x$，对它们进行排序，并且对于每个$a_i$，按顺序测试每个除数的整除性，直到找到一个不能整除的除数$a_i$。 这是正确的，因为答案的定义明确需要最小的此类除数。 

一旦我们估算了成本，瓶颈就显而易见了。 如果$x$有$D$除数，那么每个查询可能需要最多$D$模数检查。 在最坏的情况下$D$可以很大，并且与$n$最多$10^6$，如果每个查询都扫描一个大前缀，这会变得太慢。 

关键的结构简化来自于我们实际上不需要每个查询的完全分解。 对于固定的$a_i$，除数$x$那个鸿沟$a_i$正是那些除数$\gcd(x, a_i)$。 这将问题转化为检查除数集中的成员资格：除数$d$有效期为$a_i$当且仅当它不整除$\gcd(x, a_i)$。 

所以对于每个查询，我们计算$g = \gcd(x, a_i)$，然后扫描除数$x$按升序排列并返回第一个除数$d$这样$d \nmid g$。 这取代了重复的完全可分性检查$a_i$并针对较小的数字进行检查。 

我们仍然扫描排序的除数列表，但这现在是对预先计算的结构的简单线性传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（每个查询重新计算除数）|$O(n \sqrt{x})$|$O(1)$| 太慢了 |
 | 除数枚举+gcd剪枝|$O(D + nD)$最坏的情况|$O(D)$| 实践中接受|

 ## 算法演练

 1. 计算所有除数$x$通过检查整数$\sqrt{x}$。 对于每个有效的除数对，将两个值插入到列表中。 

目标是为以下人员建立准确的候选人集$z$。 
2. 按升序对除数列表进行排序。 

这种排序至关重要，因为该问题需要最小的有效除数。 
3.对于每个查询值$a_i$, 计算$g = \gcd(x, a_i)$。 

这压缩了有关哪些除数的所有信息$x$也分$a_i$变成一个数字。 
4. 迭代已排序的除数$x$从最小到最大。 
5. 对于每个除数$d$，检查是否$g \bmod d = 0$。 

如果它不为零，$d$不分开$a_i$， 所以$d$是此查询的答案。 
6. 如果扫描完成后没有找到这样的除数，则输出$-1$。 

重要的设计选择是我们从不重新计算整除性$a_i$直接地。 所有成员资格查询都简化为检查除数是否为$x$也分$g$。 

### 为什么它有效

 对于任意除数$d$的$x$，条件“$d$划分$a_i$” 相当于“$d$划分$\gcd(x, a_i)$”。这个等价成立，因为任何除数$x$划分$a_i$必须除以它们的最大公约数。 

因此，每个查询的除数列表自然分为两部分：$g$，以及那些没有的。 由于我们按升序扫描，除数集之外的第一个除数$g$正是最小的有效答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from math import gcd

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))
    
    # compute divisors of x
    divs = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            divs.append(i)
            if i * i != x:
                divs.append(x // i)
        i += 1
    
    divs.sort()
    
    for ai in a:
        g = gcd(x, ai)
        ans = -1
        for d in divs:
            if g % d != 0:
                ans = d
                break
        print(ans)

if __name__ == "__main__":
    solve()
```第一步构建完整的除数列表$x$在$O(\sqrt{x})$。 这只需要执行一次，这很重要，因为$x$在所有查询之间共享。 

内部循环使用 gcd 来避免检查整除性$a_i$直接地。 条件`g % d != 0`是关键替代品`ai % d != 0`，重复推理的成本会更高。 

早期中断确保一旦找到最小的无效除数，我们立即停止扫描。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(\sqrt{x} + nD)$| 除数生成一次，每个查询都会扫描除数列表 |
 | 空间|$O(D)$| 存储所有除数$x$|

 除数计数$D$受约数个数的限制$x$，在典型情况下是可以管理的。 由于一旦发现第一个不匹配，每个查询都会提前停止，因此平均性能明显优于最坏情况的界限，使得该解决方案适合$n = 10^6$。

 ## 边缘情况

 当$a_i$是每个除数的倍数$x$，算法计算$g = x$，并且每个除数都通过了检查`g % d == 0`。 扫描完成，没有中断并正确返回$-1$，匹配定义。 

什么时候$x$是质数，除数列表是`[1, x]`。 因为 1 总是整除任何$a_i$，答案是$x$（如果$a_i$不能被整除$x$） 或者$-1$。 该算法自然会处理这个问题，因为它首先检查 1，然后直接到达$x$。 

什么时候$a_i$非常小，尤其是 1，gcd 变为 1。由于只有除数 1 能整除 1，因此 的所有其他除数$x$立即成为候选答案，因此算法返回第二小的除数$x$，它与定义完全匹配。
