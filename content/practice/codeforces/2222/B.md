 ## 解决方案
 ## 问题理解

 我们得到一个整数数组和一系列操作。 每个操作都包含两个概念部分：首先，您可以围绕数组中任何选定的中心对称地交换元素，从而有效地让您以受控的方式重新排序元素； 其次，根据操作输入标记特定元素。 重要的是，标记保持附加到元素本身，而不是它的位置，因此未来的交换不会取消它的标记。 在所有操作之后，任务是最小化未标记元素的总和。 

第一个关键观察是对称交换不受限制，因为对于每个操作，可以自由选择间隔长度。 这意味着，原则上，只要不违反数组边界，数组就可以任意重新排列。 因此，交换的确切顺序并不限制算法 - 唯一相关的限制是标记哪些元素。 

输入约束允许每个测试集最多 10^5 个元素和 10^5 个操作，以及最多 10^4 个测试用例。 对所有交换进行简单的模拟是不可行的，因为在最坏的情况下，每次交换都可能是 O(n)。 我们需要一种避免完全模拟交换并专注于未标记元素的方法。 

当所有元素均为负数时，就会出现一个重要的边缘情况。 粗心的方法可能会尝试选择最大的元素来保留未标记的元素，但最佳策略始终是标记最大的元素，以留下尽可能小的未标记元素之和。 

## 方法

 暴力方法很简单：对于每个操作，围绕所选中心执行对称交换，然后标记指定元素。 完成所有操作后，迭代数组以对未标记的元素求和。 这种方法是正确的，因为它忠实地实现了问题规则，但在最坏情况下其时间复杂度为 O(m * n)。 当 n 和 m 达到 10^5 时，这将需要多达 10^10 次操作，这超出了时间限制几个数量级。 

关键的见解是对称交换不限制最终标记哪些元素。 由于我们可以任意交换元素，因此我们总是可以将最大的元素移动到将被标记的位置。 因此，问题简化为一个更简单的任务：识别将被标记的元素，如果可能的话选择其中最大的元素，并计算剩余元素的总和。 

具体来说，我们需要：

 1. 收集所有将被标记的索引。 
2. 对数组进行排序。 
3. 标记最大的元素（最多为标记索引的数量），以最小化未标记元素的总和。 

由于排序，这将问题从 O(m * n) 减少到 O(n log n)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(m * n) | O(n) | 太慢了 |
 | 最佳 | O(n log n + m) | O(n log n + m) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，读取数组长度`n`和操作次数`m`。 
2.读取数组`a`以及操作索引列表`x`。 
3. 使用长度的布尔数组跟踪所有标记的元素`n`或一套。 标记与输入索引相对应的每个元素。 由于标记是基于元素的，因此重复并不重要。 
4. 按升序对数组进行排序。 
5. 计算已标记的元素总数。 
6. 未标记元素的最小可能总和是通过对第一个元素求和获得的`n - marked_count`已排序数组的元素。 这是可行的，因为我们可以任意交换元素，因此最大的元素总是可以被标记。 
7. 打印总和。 

为什么它有效：不变的是交换允许根据标记的元素对数组进行任何排列。 因此，唯一重要的决定是标记哪些元素。 通过标记最大的元素，剩余的未标记元素的总和最小化。 排序保证我们可以在 O(n log n) 时间内选择总和的最小元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        x = list(map(int, input().split()))
        
        marked = [False] * n
        for idx in x:
            marked[idx - 1] = True  # convert to 0-based index
        
        marked_count = sum(marked)
        a.sort()
        unmarked_sum = sum(a[:n - marked_count])
        print(unmarked_sum)

if __name__ == "__main__":
    solve()
```该代码首先初始化一个布尔数组来跟踪哪些元素被标记。 对于 Python，输入中从 1 开始的索引将转换为从 0 开始的索引。 对标记的元素进行计数后，对数组进行排序确保我们可以选择最小的`n - marked_count`未标记总和的元素。 这避免了完全模拟交换，并且边界问题通过简单的求和计算来处理。

 ## 边缘情况

 如果所有元素均为负数，算法仍会标记最大的元素，而不会标记最小的负数。 对于单元素数组，标记它会导致零和。 处理重复项是因为标记跟踪元素本身； 指向同一元素的多个索引不会过度计数。 

输入：```
1
5 5
-5 -1 -3 -2 -4
1 2 3 4 5
```排序数组：`[-5,-4,-3,-2,-1]`。 所有元素均已标记； 未标记的总和 = 0。算法正确计算出 0。 

这证实了否定、重复和边界场景的正确性。
