 ## 解决方案
 ## 问题理解

 我们得到一个长整数序列，并且允许我们从中选择一个子序列。 目标不仅仅是最大化子序列的长度，而且对所选元素的重复方式施加非常具体的结构约束。 

构造的序列的长度必须能被四整除。 如果我们将其分为四个连续元素的块，则每个块必须具有第一个和第三个元素相等、第二个和第四个元素相等的模式。 所以每个块看起来像`x, y, x, y`，不同的块是相互独立的，只不过我们是按顺序从原始数组中选择所有元素。 

我们希望这种形式的最长可能序列作为子序列。 

输入大小最多可达 500,000 个元素，因此任何尝试以二次方式显式枚举对或构造子序列的解决方案都将立即失败。 该结构表明我们正在选择重复值并将它们以受约束的模式配对，因此关键的困难在于计算有多少有效值`x, y`可以在尊重顺序的同时形成重复。 

一个微妙的失败案例来自贪婪配对而没有正确跟踪重用。 例如，在`1 2 1 2 1 2`，很容易贪婪地形成`(1,2,1,2)`重复，但根据配对的使用方式，天真的方法可能会过度使用出现次数或无法跨块重用最佳配对。 

当某个值多次出现但配对选择发生冲突时，就会出现另一种边缘情况。 例如，在`1 1 1 1 1 1`，粗心的配对策略可能会交替配对早期出现的情况并阻止后来更好的组合，即使最佳解决方案只是形成重复的`(1,1,1,1)`块。 

## 方法

 强力解释将尝试逐步构建子序列，决定每对位置是否将它们匹配为`(x, y, x, y)`阻止或跳过元素。 这很快就会呈指数增长，因为每个元素都可以参与多个潜在的配对，并且早期决定会影响以后的所有可能性。 

一个稍微好一点的天真的想法是固定两个值`x`和`y`，然后贪婪地扫描数组，提取尽可能多的`x, y, x, y`尽可能的模式。 如果对所有值对执行此操作仍然太慢，因为最多可能有`O(n)`独特的价值观和潜在的`O(n^2)`对。 

关键的观察结果是答案的结构仅取决于值的配对出现，而不取决于值本身。 每个块消耗两次`x`并且出现两次`y`。 所以对于任意固定对`(x, y)`，最大块数取决于我们可以按顺序匹配出现的次数。 这将问题简化为序列中配对出现的问题。 

我们可以利用每个有效块对应于选择两个值的事实，而不是显式测试所有对`x`和`y`并按顺序贪婪地将它们的出现配对。 标准技巧是为每个值维护其位置列表，然后考虑两个列表可以交错的频率。 

更深入的见解是，最优构造减少为重复提取有效对`(x, y)`这样我们就可以找到两次出现的情况`x`和其中的两个`y`按增加的索引顺序，然后从将来的考虑中删除这些事件。 该结构相当于重复形成不相交的匹配索引对，然后再次将这些对配对。 

这导致了一个贪婪的过程，我们维护可用的未使用位置并按顺序重复构建相等值对，然后将对组合成块。

 | --- | --- | --- | --- |
 | 蛮力 | O(n²) 或更糟 | O(n) | 太慢了 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 按升序对每个值的所有索引进行分组。 每个值都会提供一个它出现的位置列表。 这允许我们在形成对时独立地处理每个值。 
2. 对于每个值，每次重复出现两次并形成候选对。 每个这样的对都代表最终构造中的一个潜在端点。 
3. 全局收集所有此类对，按其首次出现索引排序。 这些对代表保留子序列顺序的可用“边”。 
4. 现在将每一对视为一个令牌。 我们想要形成两个标记的序列`(x, y)`这样我们就可以找到两个标记`x`和两个令牌`y`，尊重顺序约束。 
5. 维护一个贪婪的结构，按顺序扫描这些配对令牌，并尝试形成长度为 2 的链，并标记使用情况。 
6. 每次我们成功匹配两对`x`和两对`y`按顺序，我们输出一个块`x, y, x, y`。 
7. 继续，直到不再存在有效组合。 

关键的推理步骤是我们将原始序列压缩为可重用的对单元，然后以递增的索引顺序贪婪地匹配它们。 这避免了全局组合搜索，同时保留了可行性约束。 

### 为什么它有效

 每个有效块需要出现四次，形成两个等值对。 任何解决方案都可以分解为不相交的相等值对，因为等式约束强制重复使用相同的值。 一旦事件按顺序最佳配对，唯一剩下的自由就是如何将这些对分组为`(x, y)`块。 贪心构造确保只要两个兼容对按顺序存在，使用它们就不会阻止更好的未来解决方案，因为所有其他块仅依赖于序列中较晚的剩余未使用的出现。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pos = {}
    for i, v in enumerate(a):
        pos.setdefault(v, []).append(i)

    pairs = []
    for v, lst in pos.items():
        for i in range(0, len(lst) - 1, 2):
            pairs.append((lst[i], lst[i+1], v))

    pairs.sort()

    used = [False] * len(pairs)

    res = []

    j = 0
    m = len(pairs)

    while j < m:
        if used[j]:
            j += 1
            continue

        i1, i2, v1 = pairs[j]
        used[j] = True

        k = j + 1
        while k < m and used[k]:
            k += 1

        if k == m:
            break

        j1, j2, v2 = pairs[k]
        used[k] = True

        res.extend([v1, v2, v1, v2])

        j = k + 1

    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```该代码首先将每个值压缩为不相交的相邻索引对。 这确保我们永远不会重复使用相同的事件两次。 按第一个索引排序保留了子序列顺序约束。 

然后，贪婪循环重复选择最早的可用对并将其与下一个可用对进行匹配。 每场成功的比赛都会产生一个有效的`x, y, x, y`堵塞。 这`used`数组确保每个出现对最多使用一次。 

一个微妙的点是在搜索下一个候选者时跳过已经使用的对。 否则，算法可能会意外地重复使用一对或破坏排序一致性。

 ## 边缘情况

 一种故障模式来自出现奇数次的值。 例如，`1 1 1`不能贡献超过一对可用的对，并且必须忽略剩余的出现。 将位置两两分组的配对步骤会自动丢弃多余的出现，确保不会出现无效的重用。 

另一种情况是存在对，但索引顺序交错得很差。 例如，`1 2 1 3 2 3`需要尊重跨值的排序约束。 按首次出现对对进行排序可以保证我们在选择连续的可用对时不会违反子序列排序。 

最后的边缘情况是仅存在一对时。 在这种情况下，没有第二对可以匹配，并且算法正确地输出零长度，因为当没有伙伴对可用时循环终止。
