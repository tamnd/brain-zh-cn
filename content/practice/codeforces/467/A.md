 ## 解决方案
 ## 问题理解

 问题提出了一个简单的场景：乔治和亚历克斯想一起找一间宿舍。 宿舍中的每个房间都有当前入住人数和最大容纳人数。 输入给出了房间数量，以及每个房间的当前居住人数和总容量。 任务是计算有多少个房间可以同时容纳乔治和亚历克斯。 

限制很小：最多有 100 个房间，每个房间的容量不超过 100。这意味着任何单独检查每个房间的算法，即使有一些嵌套检查，也将在时间限制内顺利运行。 由于数字都是小整数，因此不存在整数溢出或精度问题的风险。 

当房间几乎满员时，就会出现一种微妙的边缘情况。 例如，一个可容纳 2 人和 1 人的房间只能再容纳一个人，因此乔治和亚历克斯不能同时入住。同样，如果一个可容纳 2 人的房间是空的，那么它正好可以容纳两个人。 不检查“两个空间”条件将产生不正确的结果。 

## 方法

 蛮力方法很简单。 对于每个房间，通过从容量中减去当前占用者来计算可用空间。 如果可用空间至少为 2，则增加计数器。 由于最多有 100 个房间，因此最多需要 100 次简单的算术检查，这对于现代计算机来说是微不足道的。 没有更快的渐近方法，因为我们必须至少检查每个房间一次。 关键的见解是认识到“房间可以容纳两者”简化为简单的比较`q_i - p_i >= 2`。 这种小小的简化消除了任何不必要的簿记或复杂的逻辑。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 已接受 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 问题很简单，暴力解决方案也是最优的。 

## 算法演练

 1.读取整数`n`，房间数量。 
2. 初始化计数器`count`为零。 这将跟踪可容纳乔治和亚历克斯的房间数量。 
3.对于接下来的每一个`n`线路：

 1.读取当前入住人数`p`以及房间的容量`q`。 
2. 计算可用空间为`q - p`。 
3. 如果可用空间至少为 2，则增加`count`1.
 4.处理完所有房间后，打印`count`。 

工作原理：在每一步，算法都会准确检查乔治和亚历克斯入住所需的条件：房间必须至少有两个可用空间。 由于所有房间均已考虑在内且每个房间均经过独立评估，因此最终计数准确地反映了所有有效房间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
count = 0

for _ in range(n):
    p, q = map(int, input().split())
    if q - p >= 2:
        count += 1

print(count)
```解决方案直接遵循算法。 该循环遍历每个房间，从容量中减去当前占用率，如果有两个或更多空间可用，则增加计数器。 的选择`q - p >= 2`直接实现问题的要求。 使用快速 I/O 是较大输入大小的预防措施，但对于`n ≤ 100`这并不是绝对必要的。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    count = 0
    for _ in range(n):
        p, q = map(int, input().split())
        if q - p >= 2:
            count += 1
    return str(count)

 ## 边缘情况

 如果一个房间的当前居住者为零，但容量小于 2，则它不能容纳两者，例如，`p=0, q=1`。 算法正确计算`q - p = 1 < 2`， 所以`count`不增加。 对于正好剩下两个空间的房间，`p=1, q=3`，算法计算`q - p = 2`, 递增`count`正确。 已满员的房间将被自动忽略。 这证实了比较`q - p >= 2`正确处理所有微妙的占用情况。
