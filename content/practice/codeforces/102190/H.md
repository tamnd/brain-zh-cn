 ## 解决方案
 ## 问题理解

 这个时钟上的一天包含`h`小时，并且每个小时包含`m`分钟。 显示的时间由小时数标识`x`和分钟数`y`， 在哪里`0 <= x < h`和`0 <= y < m`。 

当一分钟的分钟数至少等于它的小时数时，一分钟就被归类为花水，所以条件很简单`y >= x`。 每对`(x, y)`代表一天中的一分钟，因为秒无关紧要。 任务是找到满足此条件的所有分钟的分数，并以最低的形式打印该分数。 

有`h * m`显示的总分钟数。 既然两者`h`和`m`可以大到`10^9`，该产品可以达到`10^18`。 更重要的是，每小时或每分钟迭代一次最多需要`10^9`操作，同时迭代每一对`(x, y)`最多需要`10^18`运营。 解决方案必须将算术运算的计数减少到恒定数量。 

第一个边界情况是当`h = m = 2`。 这四个时间分别是`(0,0)`,`(0,1)`,`(1,0)`， 和`(1,1)`。 三满足`y >= x`，所以答案是`3/4`。 粗心的实现使用`y > x`只会算`(0,1)`并生产`1/4`。 

例如，当时间多于分钟时，会出现另一种边界情况`7 2`。 对于小时数`0`和`1`，有些分钟符合条件，但对于从`2`通过`6`，没有一分钟可以满足`y >= x`因为最大的分钟数只有`1`。 正确的结果是`3/14`。 假设每小时至少贡献一分钟花水的实现会多算。 

相反的情况也很重要。 为了`2 7`， 小时`0`已完成全部 7 分钟排位赛，而 1 小时`1`有六个，给予`13`排位赛分钟数`14`， 或者`13/14`。 不平等包含平等，所以`(1,1)`必须计算。 使用严格比较会错误地给出`12/14 = 6/7`。 

## 方法

 直接的方法是检查每个显示的时间`(x, y)`并测试是否`y >= x`。 正好有`h * m`这样的对，所以虽然该方法显然是正确的，但其最坏情况的操作计数是`10^18`。 即使在一次恒定时间操作中检查一对也远远超出了任何实际比赛的限制。 

我们可以通过固定小时数并以数学方式计算有效的分钟数来做得更好。 对于固定的时间`x`，条件是`y >= x`。 如果`x >= m`, 没有有效的`y`，因为每分钟数最多`m - 1`。 如果`x < m`，有效的分钟数是`x, x + 1, ..., m - 1`，准确给出`m - x`有效分钟数。 

只有第一个`min(h, m)`小时数可以做出贡献。 让`k = min(h, m)`。 花水分钟数为`m + (m - 1) + ... + (m - k + 1)`。 

这是一个算术级数`k`条款。 其总和为`k * (2m - k + 1) / 2`。 

分母就是总分钟数，`h * m`。 然后，我们使用最大公约数减少所得分数。 

关键的观察是，二维计数问题实际上是一个一维算术级数。 比较`y >= x`创建一个三角形区域`h x m`grid，可以直接计算其大小，而不需要访问其单元格。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(hm)| O(1) | O(1) | 太慢了 |
 | 最佳| O(log(hm)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`h`和`m`，然后设置`k = min(h, m)`。 仅小时数`0`通过`k - 1`可以有至少一个有效的分钟数。 
2. 计算花水分钟数为`k * (2m - k + 1) / 2`。 这是捐款的总和`m, m - 1, ..., m - k + 1`。 
3. 计算总分钟数为`h * m`。 每个小时恰好包含`m`分钟。 
4. 将分子和分母除以最大公约数。 输出必须是约化分数而不仅仅是等值分数。 
5. 打印简化后的分子，然后打印`/`和减少的分母。 

### 为什么它有效

 每小时`x < min(h, m)`，恰好是分钟数`x`通过`m - 1`满足`y >= x`，因此该小时贡献`m - x`花水分钟。 对于每一个`x >= m`，它的贡献为零。 因此，完整的计数正是算法所求和的算术级数。 将此计数除以总数`h * m`给出所需的比例，并将两个值除以它们的 gcd 产生唯一的约简分数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from math import gcd

def solve():
    h, m = map(int, input().split())

    k = min(h, m)

    numerator = k * (2 * m - k + 1) // 2
    denominator = h * m

    g = gcd(numerator, denominator)

    print(numerator // g, denominator // g)

if __name__ == "__main__":
    solve()
```价值`k`捕获计数中唯一相关的边界。 如果`h <= m`，每个小时都可以贡献，所以`k = h`。 如果`h > m`，只有第一个`m`小时可以贡献，所以`k = m`。 

分子使用等差数列公式而不是循环。 划分由`2`在 gcd 约简之前执行，但乘积始终是偶数，因为以下之一`k`和`2m - k + 1`是均匀的。 Python 整数还可以安全地处理最大的中间值，因此不存在溢出问题。 

表达式`m - x`包括端点`y = x`，匹配`>=`健康）状况。 这正是严格比较会引入相差一错误的地方。 

最后，`gcd`减少分数。 例如，原始结果为`h = 13, m = 11`是`66/143`，他们的 gcd 是`11`, 给予`6/13`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(log(hm)) | 计算 gcd 需要对数时间； 所有其他操作都是恒定时间。 |
 | 空间| O(1) | O(1) | 仅存储恒定数量的整型变量。 |

 约束允许值高达`10^9`，所以一个解决方案需要`O(h)`或者`O(m)`迭代可能已经需要多达十亿次操作。 该算术公式避免了所有迭代，使得除了 gcd 计算之外，运行时间实际上保持不变。 Python 的任意精度整数也可以安全地处理周围的乘积`10^18`。

 ## 边缘情况

 当`h = m = 2`，输入是`2 2`分子是`2 + 1 = 3`，而分母是`4`。 算法得到`k = 2`并计算`3/4`。 平等案例`(1,1)`被计数是因为进程从分钟开始`x`， 不是`x + 1`。 

当时间多于分钟时，请考虑`7 2`。 这里`k = 2`，所以只有几个小时`0`和`1`贡献。 他们的贡献是`2`和`1`, 给予`3`花水分钟出`14`。 输出是`3/14`。 时间`2`通过`6`通过采取自动排除`k = min(h, m)`。 

当分钟数多于小时数时，请考虑`2 7`。 在这里，两个小时都做出了贡献，`7`小时的有效分钟数`0`和`6`一个小时`1`。 分子是`13`分母是`14`，所以结果是`13/14`。 这会检查每小时是否计算分钟数字的完整有效后缀。 

对于最大相等尺寸，`1000000000 1000000000`，该算法永远不会循环遍历十亿个值。 它直接评估算术级数`k = 1000000000`，产生约简分数`500000000000000001/1000000000000000000`。 大的中间值由 Python 整数安全地表示。 

所有这些情况的中心边界条件都是相同的：小时数等于`m`没有有效的分钟，因为最大的分钟数是`m - 1`。 这就是为什么贡献小时数恰好是`min(h, m)`，而不是`min(h, m + 1)`或者`min(h, m - 1)`。
