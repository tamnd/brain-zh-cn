 ## 解决方案
 ## 问题理解

 删除所有立即可见的对后，每个等级都恰好处于三种情况之一。 两张同等级的牌可能在同一手牌中并且成对消失。 这两张牌可能会在 Brett 和 Caoimhe 之间分配，在这种情况下，该等级会为每手牌贡献一张活跃牌。 最后，恰好一个等级只剩下一张牌，那就是老处女。 该卡属于 Brett 或 Caoimhe。 

活跃配对队列的身份并不重要。 假设有 (m) 个等级，其两张牌在玩家之间平分。 每个这样的等级的行为都是相同的：每当一个玩家从另一个玩家手中拿走其牌时，两张牌立即形成一对并消失。 唯一特殊的牌是老处女，因为拿走它并不会形成一对。 

输入给出 (n) 个等级和两个字符串，描述每手中有多少个等级的牌。 我们只需要扫描一次字符串即可确定哪个玩家拥有唯一的单例以及每手牌有多少个等级。 由于测试用例上所有 (n) 的总和最多为 (10^6)，因此每个测试用例的 (O(n)) 解决方案就是预期的规模。 任何探索单个游戏历史的方法都是没有希望的，因为可能的抽签序列的数量随着活跃等级的数量呈指数增长。 

一个常见的实施错误是将总数为 2 的每个等级计为活动对。 当两张牌已经在同一手牌中时，这是错误的，因为这对牌在游戏开始之前就消失了。 例如，与```
1
2
10
01
```布雷特已经拥有两张 1 级牌，因此它们被丢弃。 唯一剩下的牌是曹伊姆赫的2级老处女，布雷特以概率（1）获胜，而不是将1级视为另一对活跃对获得的概率。 

相反的错误也是可能的。 每手一张牌的等级仍然有效，因为两个玩家最初手中都没有这对牌。 例如，```
1
2
11
11
```没有单例，也不是有效的输入，但等级结构说明了区别：每个分割等级向双手贡献一张牌，并且必须保留在游戏中，直到抽出其中一张牌为止。 

没有活动的分裂等级的情况需要单独注意。 例如，```
1
2
10
02
```丢弃第一对后，只剩下老处女了。 布雷特开始，但没有对子可以触发另一步，所以布雷特立即输了。 答案是（0）。 

## 方法

 直接模拟将保留当前玩家可能抽出的每张有效卡牌和分支。 它是正确的，因为它完全遵循游戏，但对于 (m) 个活跃排名，可能的平局历史可能呈指数级增长。 即使每个状态都被紧凑地表示，枚举历史的数量级也是 (2^m)，这对于 (10^5) 左右的 (m) 来说已经是不可能的了。 

有用的观察是所有活跃等级都是可以互换的。 我们永远不需要记住当前正在玩哪个特定的排名。 我们只需要活跃对的数量（m），轮到谁了，以及当前谁持有老女仆。 

有四种状态，由当前玩家和老处女的主人决定。 令(A_m)为当布雷特要移动并且曹伊姆赫抓住老处女时布雷特最终获胜的概率。 设(B_m)为Caoimhe要移动并且Brett抱着老处女时的概率。 其他两种状态只需通过一个普通的动作即可获得。 

假设布雷特要搬家，而曹伊姆赫拥有老姑娘。 布雷特看到曹伊姆赫手中有(m+1)张牌，其中包括(m)张普通牌和老处女。 他以 (1/(m+1)) 的概率带走老姑娘。 他以 (m/(m+1)) 的概率取出一张普通牌并移除一对有效牌。 

当曹伊姆赫要搬家而布雷特拥有老处女时，类似的论点也适用。 这些转变形成一个小的线性递归。 关键的简化在于（m）级的两个状态可以直接从（m-1）级的两个状态求解，因此不需要大型动态规划表。 

递归式可以写成

 [
 A_m=\frac{(m+1)A_{m-1}+B_{m-1}}{m+2},
 ]

 和

 [
 B_m=\frac{A_{m-1}+(m+1)B_{m-1}}{m+2}。 
]

 基态为 (A_0=1) 和 (B_0=0)。 由于没有剩余的活跃对，如果Caoimhe拥有老处女，那么Brett就赢了，而如果Brett拥有它，那么他就输了。 

最初的起始状态是轮到布雷特。 如果草木河拥有老处女，答案是（A_m）。 如果 Brett 拥有它，则 Brett 刚刚进行了第一次移动状态转换，因此答案是 (B_{m-1})。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(2^m)) | (O(米)) | 太慢了|
 | 最佳| (O(n)) | (O(n)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 扫描所有排名并计数`pairs`，两个字符串都包含一张卡片的位置数。 这些正是在最初对删除后作为活跃对幸存下来的排名。 同时，找到总数为1的唯一位置，并记录Brett或Caoimhe是否拥有该卡。 
2. 初始化零个活动对的动态编程值。 设置（A_0=1），因为没有活跃对子且曹伊姆赫持有老处女，布雷特获胜。 设置（B_0=0），因为没有活跃的对子并且 Brett 拿着老处女，Brett 输了。 
3. 对于从 (1) 到 (1) 的每 (m)`pairs`，使用更新两个概率
 [
 A_m=\frac{(m+1)A_{m-1}+B_{m-1}}{m+2}
 ]
 和
 [
 B_m=\frac{A_{m-1}+(m+1)B_{m-1}}{m+2}。 
]
 因子(m+1)代表相关转换中的所有普通牌，而剩下的一项代表抽到老处女。 
4. 如果老女仆属于Caoimhe，则输出(A_m)，因为实际游戏开始时Brett正是以该状态移动。 
5. 如果老女仆属于Brett且(m=0)，则输出(0)，因为没有剩下对，Brett和老女仆被困住了。 否则输出(B_{m-1})，对应于Caoimhe获得第一个概率机会拿走老处女之前Brett的第一个确定性普通抽签。 

### 为什么它有效

 不变的是，在每个完成的回合后，每个幸存的普通等级都向每手牌贡献一张牌。 因此，游戏的整个普通部分完全由幸存等级的数量来描述。 老女仆是唯一一张行为不同的牌，因此了解其所有者和轮到的玩家完全决定了未来的概率。 每次转换都会考虑当前玩家可以抽出的每种可能的牌类型，并且最终的状态要么减少一对活跃牌，要么与转移的老女仆的牌对数量相同。 因此，重复性只考虑了每个可能的游戏延续一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n, b, c):
    pairs = 0
    old_owner = -1

    for i in range(n):
        x = ord(b[i]) - 48
        y = ord(c[i]) - 48

        if x == 1 and y == 1:
            pairs += 1
        elif x + y == 1:
            old_owner = 0 if x == 1 else 1

    if pairs == 0:
        return 0.0 if old_owner == 0 else 1.0

    a = 1.0
    d = 0.0

    for m in range(1, pairs + 1):
        na = ((m + 1) * a + d) / (m + 2)
        nd = (a + (m + 1) * d) / (m + 2)
        a, d = na, nd

    if old_owner == 1:
        return a

    return d

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        b = input().strip()
        c = input().strip()

        ans = solve_case(n, b, c)
        out.append("{:.15f}".format(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```字符串上的第一个循环恰好执行从原始手到小概率状态的结构还原。 一个位置包含`1`两个字符串中都是活跃的对。 总和为 1 的位置标识了老处女及其所有者。 职位包含`2`一只手牌被忽略，因为他们的两张牌已经形成一对并消失了。 

变量`a`和`d`仅存储先前级别的重复。 更新必须对两个新状态使用旧值，因此代码计算`na`和`nd`在将它们分配回来之前。 更新中`a`首先，然后在计算时使用新值`d`会默默地引入错误的依赖。 

Python 的浮点类型在这里就足够了，因为每个运算都是少量的加法、乘法和除以整数。 所需的误差容限为 (10^{-9})，而递归在数值上仍表现良好，因为每个值都位于区间 ([0,1]) 内。

 ## 边缘情况

 在访问 (m-1) 处的递归之前必须处理零对情况。 如果 Brett 拥有单例并且没有分裂等级，则没有什么可抽的并且 Brett 立即失败。 和`b = 10`和`c = 02`，答案正是`0`。 

如果Caoimhe拥有单张并且没有分裂等级，则Brett已经获胜，因为唯一幸存的牌在Caoimhe手中。 和`b = 01`和`c = 10`，答案正是`1`。 

一张手上有两张牌的等级不得贡献`pairs`。 例如，在`b = 20`和`c = 01`，两张 1 级牌在 Brett 手中已经是可见的一对，并在游戏开始前消失。 将该排名算作活跃排名会改变每个后续分母。 

每手一张牌的等级必须恰好贡献一对有效对。 这两张牌最初不能被丢弃，因为两个玩家都没有这两张牌。 它们会一直留在游戏中，直到一个玩家抽取另一个玩家的副本。 

递归也同时需要先前的值。 因此，在替换旧的对之前，实现会将两个下一个值计算到临时变量中。 这避免了一个微妙的求值顺序错误，该错误会使第二次循环使用 (A_m) 而不是 (A_{m-1})。
