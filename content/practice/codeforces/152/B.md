 ## 解决方案
 ## 问题理解

 我们有一个矩形网格`n`行和`m`列。 Vasya 起始位置`(xc, yc)`。 然后他处理`k`运动向量一一对应。 

对于向量`(dx, dy)`，他反复动作：```
(x, y) -> (x + dx, y + dy)
```他继续朝那个方向移动，直到下一步移动离开网格。 完成一个向量后，他从当前位置开始下一个向量。 

任务是计算所有向量的有效移动总数。 

网格尺寸可以大到`10^9`，这立即排除了对网格本身单元格的任何模拟。 单个向量也可以将 Vasya 移动到大约`10^9`次，因此不可能进行逐步模拟。 虽然`k`只是`10^4`，所执行的动作总数可能是巨大的。 

核心观察是，对于每个向量，我们实际上不需要模拟运动。 我们只需要确定在一个坐标离开有效范围之前可以应用向量多少次。 

一些边缘情况很容易被错误处理。 

假设运动是纯垂直的。 

输入：```
5 5
3 3
1
-2 0
```正确答案是：```
1
```Vasya 移动一步后到达`(1, 3)`。 另一个动作将达到`(-1, 3)`，在网格之外。 粗心的解决方案同时除以两者`dx`和`dy`如果不单独处理零将会崩溃或产生垃圾。 

负面方向是另一个常见的错误来源。 

输入：```
5 5
4 4
1
-1 -2
```正确答案是：```
1
```Vasya 移动一步后到达`(3, 2)`。 另一个动作将达到`(2, 0)`，这是无效的，因为列`0`不存在。 如果公式假设所有方向均为正，则计算出的步数将变得不正确。 

也有根本无法移动的情况。 

输入：```
3 3
1 1
1
-1 0
```正确答案是：```
0
```第一步已经离开棋盘。 某些实现会意外地产生负数步骤并将其添加到答案中。 

最后，答案本身可能会变得非常大。 尺寸可达`10^9`直至`10^4`向量，移动总数可能超过 32 位整数范围。 Python 会自动处理这个问题，但 C++ 解决方案必须使用`long long`。 

## 方法

 最直接的解决办法就是逐字模拟每一个动作。 对于每个向量`(dx, dy)`，我们反复检查是否`(x + dx, y + dy)`保留在板内。 如果是，我们就移到那里并增加答案。 

这种暴力方式是正确的，因为它完全遵循游戏规则。 问题是运行时间。 单个向量可能产生近`10^9`移动。 和`10^4`向量，总工作量可达`10^13`操作，远远超出了2秒内所能完成的范围。 

关键的观察结果是沿着一个向量的运动是完全可预测的。 如果瓦西亚在`(x, y)`并使用向量`(dx, dy)`， 后`t`他将进行的动作：```
(x + t * dx, y + t * dy)
```我们需要最大的非负整数`t`这样两个坐标都保留在网格内。 

这意味着：```
1 <= x + t * dx <= n
1 <= y + t * dy <= m
```每个坐标独立地施加一个上限`t`。 最大有效步数只是这些限制中的最小值。 

例如，如果`dx > 0`， 然后：```
x + t * dx <= n
t <= (n - x) / dx
```如果`dx < 0`， 然后：```
x + t * dx >= 1
t <= (x - 1) / (-dx)
```我们也做同样的事`dy`，然后取最小允许值。 

这将每个向量从潜在的数十亿次模拟移动减少到恒定的算术量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(总步数) | O(1) | O(1) | 太慢了|
 | 最佳 | O(k) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取网格尺寸`n`和`m`。 
2.读取起始位置`(x, y)`。 
3. 初始化`answer = 0`。 
4. 处理每个向量`(dx, dy)`独立。 
5. 计算行坐标允许移动多少次。 

如果`dx > 0`，限制边界是底边：```
(n - x) // dx
```如果`dx < 0`，限制边界是顶部边缘：```
(x - 1) // (-dx)
```如果`dx == 0`，移动永远不会改变行，因此行坐标没有限制。 
6. 使用相同的逻辑计算列坐标允许移动多少次。 
7. 该向量的实际移动次数是两个坐标的最小限制。 

两个坐标必须同时保持有效，因此更严格的限制控制运动。 
8.将此值添加到`answer`。 
9. 更新当前位置：```
x += steps * dx
y += steps * dy
```10.处理完所有向量后，打印`answer`。 

### 为什么它有效

 对于固定向量`(dx, dy)`，每次移动都会改变相同的位置。 后`t`移动，位置正好是：```
(x + t * dx, y + t * dy)
```该算法计算最大的`t`两个坐标都保持在有效范围内。 任何更大的值都会违反至少一个边界，因此不可能进行更多的移动。 任何较小的值显然都是有效的。 

由于每个向量都是根据这些最大有效动作精确处理的，因此该算法完美地再现了游戏规则。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
x, y = map(int, input().split())

k = int(input())

answer = 0

INF = 10**30

for _ in range(k):
    dx, dy = map(int, input().split())

    steps_x = INF
    steps_y = INF

    if dx > 0:
        steps_x = (n - x) // dx
    elif dx < 0:
        steps_x = (x - 1) // (-dx)

    if dy > 0:
        steps_y = (m - y) // dy
    elif dy < 0:
        steps_y = (y - 1) // (-dy)

    steps = min(steps_x, steps_y)

    answer += steps

    x += steps * dx
    y += steps * dy

print(answer)
```实现直接遵循数学推导。 

对于每个向量，我们独立计算沿行和列的最大有效移动。 价值`INF`代表永不改变的坐标的“无限”移动。 例如，如果`dx == 0`，行坐标永远不会离开网格，因此只有列约束很重要。 

公式根据方向符号的不同而不同。 当正向下移动时`dx`，底部边界`n`成为限制因素。 当负值向上移动时`dx`，顶部边界`1`成为限制因素。 

更新步骤：```
x += steps * dx
y += steps * dy
```很重要。 当前向量结束后，下一个向量从最终位置开始。 

Python 整数自动安全地处理非常大的答案。 在具有固定宽度整数的语言中，答案必须使用 64 位存储。

 ## 边缘情况

 考虑一个坐标永远不会改变的运动。 

输入：```
5 10
3 2
1
0 3
```算法集`steps_x = INF`因为`dx = 0`。 对于立柱移动：```
(10 - 2) // 3 = 2
```所以最终的答案是`2`。 动作是：```
(3,2) -> (3,5) -> (3,8)
```另一个动作将到达柱子`11`，在网格之外。 

现在考虑负向运动。 

输入：```
5 5
4 4
1
-1 -2
```对于行：```
(4 - 1) // 1 = 3
```对于列：```
(4 - 1) // 2 = 1
```最小值是`1`，因此只能进行一次移动。 搬到后`(3,2)`，另一个动作将尝试`(2,0)`，这是无效的。 

最后，考虑完全受阻的举动。 

输入：```
3 3
1 1
1
-1 0
```对于行：```
(1 - 1) // 1 = 0
```对于柱子来说，移动不受限制，因为`dy = 0`。 

最小值变为`0`，因此算法不执行任何移动，并且保持答案不变。
