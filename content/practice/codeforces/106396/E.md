 ## 解决方案
 ## 问题理解

 我们有两个相同长度的整数数组。 每个位置都包含一对数字，我们可以执行特定的归约操作，其本质上是通过减去较小的值来不断替换较大的值，类似于重复的欧几里德减法。 

该过程可以应用于整个结构，直到其稳定，目标是确定在所有位置上完全用尽所有此类减少后可以实现的最终值。 

该任务不是跟踪整个动态过程，而是计算一个整数，该整数总结了在最佳应用所有允许的操作后系统的最终可达状态。 

尽管该语句是通过重复转换来表达的，但关键输出只是从两个数组的相应元素之间的关系得出的一个数字。 

从约束的角度来看，输入大小可能足够大，以至于所描述的重复减法过程的任何模拟都会太慢。 从字面上模拟每个缩减步骤的简单方法可能会退化为每个操作的线性缩减，从而在聚合多个元素时导致二次或更糟糕的行为。 

唯一可行的解​​决方案必须将重复的转换压缩为每个索引的直接算术计算，然后在线性时间内组合这些结果。 

当相应元素之间的所有差异均为零时，会出现微妙的边缘情况。 在这种情况下，每对都已经平衡，答案显然应该为零。 错误地初始化累加器或跳过绝对值的幼稚实现可能会产生不正确的负值或未初始化的结果。 例如，如果所有对都相同，例如`a = [5, 5]`和`b = [5, 5]`，正确的输出是`0`，不是未定义或剩余的累加器值。 

另一种边缘情况是差异很大时，例如`a = [1, 100]`和`b = [50, 0]`。 如果粗心地单独对待对而不通过共享的不变量将它们组合起来，就会错过将所有对联系在一起的全局结构。 

## 方法

 暴力解释遵循问题中描述的字面过程。 对于每一对，我们重复在较大值和较小值之间进行减法，直到该对稳定为止。 这本质上是独立应用于每一对的欧几里得算法。 然而，如果直接实现为重复减法，则在最坏的情况下，每一步可能只会将值减少一个单位，因此单个对可能会在值的大小上花费线性时间，并且对于许多对来说，这在计算上变得不可行。 

关键的观察结果是，重复减法不会改变两个数字之差的最大公约数。 每对`(a[i], b[i])`有效贡献价值`|a[i] - b[i]|`，并且所有允许的操作都保留整个系统的 gcd 结构。 我们可以计算绝对差并获取它们的 gcd，而不是模拟操作。 这是有效的，因为变换规则永远不会在差异中已经存在的素因子之外引入新的素因子，并且重复减法的行为与欧几里得算法完全相同，该算法收敛于 gcd。 

因此，整个过程分解为计算所有成对差异的单个 gcd。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n * 最大值) | O(1) | O(1) | 太慢了|
 | 差异的 GCD | O(n log V) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将整个系统简化为计算所有索引对的单个不变量。 

1. 读取两个数组的所有元素。 每个位置定义了一对重要的关系，而不是它们的绝对值。 这将焦点从个人价值观转移到差异上。 
2. 对于每个索引，计算配对值之间的绝对差。 符号是无关紧要的，因为减法运算会擦除方向，而在欧几里德归约过程中只有大小很重要。 
3. 保持正在运行的 gcd 累加器初始化为零。 从零开始确保第一个计算的差值完全初始化 gcd，没有偏差。 
4. 通过获取当前值和下一个绝对差值之间的 gcd 来迭代更新累加器。 这逐渐将每对施加的约束合并为单个一致值。 
5.处理完所有指标后，输出最终的gcd值作为答案。 

正确性来自于这样的事实：每一对都提供了“最终可实现的值必须除以此差异”形式的约束。 gcd 正是同时满足所有这些约束的最强数。 

## Python 解决方案```python
import sys
import math

def solve():
    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))
    b = list(map(int, sys.stdin.readline().split()))
    
    ans = 0
    for i in range(n):
        ans = math.gcd(ans, abs(a[i] - b[i]))
    
    print(ans)

def run(inp: str) -> str:
    import io
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import sys as _sys
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    sys.stdin = old_stdin
    return out.getvalue().strip()
```该解决方案首先读取数组和两个序列的大小。 然后它计算绝对差值的运行 gcd。 使用`math.gcd`即使对于大输入也能确保有效减少，并且用零初始化累加器可以正确处理第一个元素，而无需特殊的外壳。 

该结构避免存储中间转换的数组，因为唯一相关的状态是不断演化的 gcd。

 ## 边缘情况

 当所有对都相同时，所有差异都为零。 用于输入`a = [7, 7, 7]`和`b = [7, 7, 7]`，算法计算差异`[0, 0, 0]`。 gcd 累加器从零开始，每一步后都保持为零，产生输出`0`。 这与不需要归约并且不会出现正不变量的事实相匹配。 

当多个零之间存在单个非零差时，例如`a = [10, 10, 17]`和`b = [10, 10, 11]`，差异变为`[0, 0, 6]`。 累加器保持为零，直到最后一步，它变成`6`，正确反映只存在一个重要的约束。 

例如，当所有差异都有一个公约数时`a = [2, 8, 14]`和`b = [0, 2, 8]`，差异是`[2, 6, 6]`。 gcd 演变为`2 → 2 → 2`，证实了该不变量在累积下是稳定的，并且除了 gcd 聚合之外，索引之间不存在隐藏的相互作用。
