 ## 解决方案
 ## 问题理解

 我们得到一个数字序列，并要求计算一个取决于其中所有递增子序列的全局值。 每个有效子序列贡献的东西可以分解为它包含的每个元素的贡献，并且任务最终减少为对每个元素求和，即有多少个递增子序列“在特定的结构角色中使用它”乘以它的值。 

关键的隐藏结构是，每个递增子序列都可以被认为是“锚定”在中间的特定元素上。 一旦我们修复了一个元素，我们就可以将子序列分成两个独立的部分：一个以该元素结束的有效递增子序列，以及一个从该元素开始的有效递增子序列。 该元素的最终贡献是构建其左侧部分的方法数量和构建其右侧部分的方法数量的乘积，乘以该元素本身的值。 

输入只是一个整数列表。 输出是一个模数下的单个整数，表示上述的总加权计数。 

这些约束意味着序列长度足够大，子序列的任何二次枚举都是不可能的。 任何尝试显式枚举递增子序列或什至使用嵌套循环对每个元素进行计数的方法都将超出时间限制。 唯一可行的方向是具有对数更新的线性或近线性方法，通常涉及压缩值后的芬威克树或线段树。 

一个微妙的陷阱是忘记长度为 1 的子序列也是有效的。 对于每个元素，其左右贡献都包含空选择，这就是为什么在两个方向上都添加了一个基值。 

## 方法

 直接方法将尝试枚举所有递增子序列，并且对于每个子序列，将其贡献分配给其中的每个元素。 这在概念上是正确的，但在计算上是不可行的。 最坏情况下子序列的数量是指数级的，甚至跟踪每个元素的贡献仍然需要迭代指数级的多个结构。 

中心观察是，如果我们将每个元素的角色固定为主元，则子序列的贡献可以在其元素之间进行乘法分解。 对于固定元素，它出现的任何有效子序列都可以分为两个独立的选择：我们如何选择严格较小且在其之前的元素，以及如何选择严格较大且在其之后的元素。 这种独立性表明对位置的动态编程与对值顺序的有效前缀和后缀聚合相结合。 

对于每个元素，我们计算两个量。 第一个是以该元素结尾的递增子序列的数量。 这仅取决于其之前具有较小值的元素。 第二个是从该元素开始的递增子序列的数量，仅取决于其后具有较大值的元素。 两者都可以使用压缩值上的 Fenwick 树来计算，因为我们只需要 DP 值的前缀和后缀之和。 

计算完两个数组后，每个元素都会贡献其左右计数乘以其值的乘积。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | Fenwick DP分解| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们分三个概念阶段处理该问题：压缩值、计算左贡献、计算右贡献，然后组合。

1. 首先，将所有值压缩到一个密集范围内。 这是必要的，因为芬威克树对索引进行操作，而我们只关心相对顺序，而不关心实际大小。 压缩后，像“小于”这样的比较就变成了前缀查询。 
2. 计算左贡献数组。 我们从左到右迭代。 对于每个位置 i，我们查询有多少个有效子序列以严格小于当前值的值结尾。 该查询提供了扩展较早结束的递增子序列的所有可能方法。 我们加一来说明由元素本身组成的子序列。 然后我们将该值插入 Fenwick 树的压缩索引处，以便将来的元素可以使用它。 
3. 对称计算右贡献数组。 我们从右向左迭代。 对于每个位置 i，我们查询有多少个子序列以严格大于当前值的值开头。 我们再次为单元素子序列添加一个。 我们边走边插入 Fenwick 树。 
4. 合并结果。 对于每个元素 i，其总贡献为 left[i] 乘以 right[i]，再乘以压缩前元素的原始值。 

出现乘法是因为选择该元素作为主元的任何有效子序列都是通过独立选择左部分和右部分形成的。 

### 为什么它有效

 在每个位置，芬威克树存储在迄今为止处理的每个值索引处结束（或开始）的有效递增子序列的总数。 DP 转换依赖于这样一个事实：增加的子序列完全由左侧最后选择的值和右侧第一个选择的值决定。 由于一旦枢轴固定，这些选择是独立的，因此乘积分解是有效的。 没有子序列被重复计算，因为每个子序列都有一个唯一的主元元素，在最终求和中被计为其“中间贡献源”。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        i += 1
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        res = 0
        while i > 0:
            res += self.bit[i]
            i -= i & -i
        return res

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l)

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    vals = sorted(set(a))
    mp = {v: i for i, v in enumerate(vals)}
    a = [mp[x] for x in a]

    m = len(vals)

    left = [0] * n
    right = [0] * n

    fw = Fenwick(m)

    for i in range(n):
        left[i] = fw.sum(a[i]) + 1
        fw.add(a[i], left[i])

    fw = Fenwick(m)

    for i in range(n - 1, -1, -1):
        right[i] = fw.sum(m) - fw.sum(a[i] + 1) + 1
        fw.add(a[i], right[i])

    ans = 0
    for i in range(n):
        ans += left[i] * right[i] * vals[a[i]]

    print(ans)

if __name__ == "__main__":
    solve()
```两次使用Fenwick树，结构相同，但遍历方向不同。 在左遍中，前缀和累积了早期较小元素的贡献。 在右遍中，使用反向前缀减法来模拟后缀行为。 

这`+1`两次传递中的术语都是必不可少的，因为每个元素单独形成一个有效的子序列，如果没有它，DP 将只计算扩展而不是独立序列。 

## 工作示例

 考虑一个小数组`[1, 2, 1]`。 压缩后仍保留`[0, 1, 0]`。 

在左边的过程中，我们一步步处理。 

| 我| 价值| 芬威克状态（概念）| 左[i] |
 | --- | --- | --- | --- |
 | 0 | 0 | 空 | 1 |
 | 1 | 1 | 包含从 0 | 开始的序列 2 |
 | 2 | 0 | 包含之前的贡献 | 1 |

 在索引 1 处，我们可以扩展以 0 结尾的子序列，给出两种可能性。 在索引 2 处，仅存在平凡子序列，因为前一个 1 无法扩展到更小的值。 

在右传中：

 | 我| 价值| 可用的未来信息 | 右[i] |
 | --- | --- | --- | --- |
 | 2 | 0 | 空 | 1 |
 | 1 | 1 | 右边只有 0 | 2 |
 | 0 | 0 | 包括所有的未来| 1 |

 结合贡献可以通过正确的主元分解对所有递增子序列产生正确的加权计数。 

现在考虑`[3, 1, 2]`，压缩为`[2, 0, 1]`。 仅当不可能在较小的值之后遇到较大的值时，左侧 DP 才会增长，这显示了排序如何控制贡献流。 右侧 DP 从另一侧反映了这种行为。 

这些痕迹证实，每个元素的贡献仅取决于其前后的相对顺序，而不是绝对位置。

 ## 边缘情况

 关键的边缘情况是所有元素都相同。 在这种情况下，每个递增子序列的长度只能为一，因此每个元素独立贡献。 两个 DP 数组的每个位置的计算结果都应为 1，最终答案将成为所有元素的总和。 Fenwick 树正确地处理了这个问题，因为没有元素严格小于或大于，因此所有前缀和后缀查询都返回零，并且基数 +1 占主导地位。 

另一个微妙的情况是严格降序。 这里，每个左边的 DP 值都保持为 1，因为没有更早的元素更小。 在右侧，对称性给出相同的结果。 这证实了算法在排序约束块转换时不会错误地尝试扩展无效子序列。
