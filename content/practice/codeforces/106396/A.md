 ## 解决方案
 ## 问题理解

 我们得到一个项目集合，每个项目都有一个整数权重。 还有一个初始偏移值，其行为类似于系统中的起始余额。 该过程从该偏移量开始，每个项目最多可以选择一次。 每个选定的项目都会按其权重移动当前值，目标是了解在考虑所有项目后可以达到哪些总价值。 

任务不是要求单个可达到的目标，而是从初始偏移开始，描述处理每个项目后所有可实现的总和，然后找到一种配置，使最终结果在系统总质量周围尽可能平衡。 具体来说，如果我们想象将累积数量分成两部分，我们希望这两部分尽可能接近，并且我们将不平衡性衡量为它们之间的绝对差。 

输入大小足够小，使得伪多项式动态规划求和解是可行的。 关键的隐藏约束是所有值加上偏移量的总和决定了 DP 范围。 这立即排除了任何指数子集枚举，它会增长为 2^n 并且即使 n 约为 40 也变得不可行。 

当所有值都为零或偏移量主导所有其他值时，会出现微妙的极端情况。 例如，如果数组为 [0, 0, 0] 并且偏移量为 5，则每个子集产生相同的总数，因此答案必须为 5。如果不考虑偏移状态而错误地初始化 DP，则可能会错误地得出只有 sum 0 可达的简单实现。 

当存在单个大值时，会出现另一种边缘情况。 如果 x = 10 且 a = [7]，则可达到的总数仅为 10 和 17。最佳分割位于这两个极端之间，并且忘记使用偏移量作为有效起始和来初始化 DP 会导致完全丢失基本配置。 

## 方法

 思考问题的一个直接方法是枚举所有项目子集。 对于每个子集，从偏移量开始计算所得的总值，然后计算该总数与总和的一半的接近程度。 这是正确的，因为它探索了所有可能的组合，但本质上是指数级的。 对于 n 个项目，这需要评估 2^n 个子集，甚至计算每个子集总和也需要 O(n)，导致 O(n·2^n)，超出小限制就变得不可能。 

关键的观察是，这在结构上是一个子集和可达性问题。 我们没有显式枚举子集，而是对所有可能的和保持布尔状态。 状态dp[s]表示处理某些项的前缀后是否可以得到sum s。 每个项目都充当 0-1 背包过渡，我们可以包含或排除它，并相应地更新可达总和。 

重要的一点是初始状态不是零，而是给定的偏移量 x。 这改变了整个 DP 域，意味着所有可达到的总和都以这个起点为中心。 一旦计算出所有可达总和，最终任务就减少为找到一个最小化总累加值的两个分区之间的差异的可达总和。 

这将问题从指数枚举简化为总和范围内的伪多项式 DP，这是可以接受的，因为所有元素的总和限制了状态空间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集 | O(n·2^n) | O(n·2^n) | O(1) | O(1) | 太慢了|
 | 0-1 DP 超过总和 | O(n·S) | O(S)| 已接受 |

 ## 算法演练

 ## 1. 计算可能和的总范围

我们首先计算所有元素的总和并添加偏移量以定义最大可达值。 这定义了 DP 边界。 如果不限制这个范围，我们将不知道 DP 表必须有多大，并且转换将变得不确定。 

## 2.初始化DP表

 我们创建一个布尔 DP 数组，其中 dp[s] 指示 sum s 是否可达。 唯一可到达的初始状态是偏移值，因为在获取任何项之前，我们当前的总和正是起始偏移量。 

此初始化是整个解决方案中最重要的建模步骤，因为它将子集和问题从零转移。 

## 3. 使用 0-1 背包转换处理每个项目

 对于每个项目，我们根据之前的状态计算一个新的 DP 数组。 如果总和 j 可达，则 j + a[i] 在下一个状态可达。 我们复制之前的 DP 以保留“不获取该项目”的选择，然后应用前向转换。 

这确保了每个项目最多使用一次，因为每一层都是根据前一层构建的。 

## 4.提取最佳平衡分区

 处理完所有项目后，我们扫描所有可达到的总和。 对于每个可达总和 s，我们将其解释为分区的一侧，并计算相对于总和的不平衡度。 答案是最小绝对差。 

## 为什么它有效

 在每一步中，dp[s] 准确地表示使用从偏移量开始的已处理项的子集可实现的总和集。 该转换保留了正确性，因为每个新状态都是通过排除或包含当前项来形成的，并且不可能进行其他操作。 由于所有子集都在 DP 中隐式表示，因此对可达状态的最终扫描相当于评估每个子集，但没有显式枚举它们。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    total = sum(a) + x

    dp = [False] * (total + 1)
    dp[x] = True

    for w in a:
        ndp = dp[:]
        for s in range(w, total + 1):
            if dp[s - w]:
                ndp[s] = True
        dp = ndp

    ans = float('inf')
    for s in range(total + 1):
        if dp[s]:
            ans = min(ans, abs(total - 2 * s))

    print(ans)

if __name__ == "__main__":
    solve()
```DP 数组的大小由完整可实现的总和范围决定，该范围在开始时计算一次。 初始化 dp[x] = True 将系统锚定在偏移状态。 

转换循环使用复制的数组来确保每个项目仅应用一次。 一个常见的错误是就地更新 dp，这将允许在一次迭代中多次使用同一项目。 

最后，扫描通过将每个可达总和视为潜在的分裂点来计算最小不平衡。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n·S) | 每个项目在 DP 范围内执行一次全面扫描 |

 值 S 是所有输入权重加上偏移量的总和。 这通常受到限制，以便 n·S 保持在几亿次或更少的操作范围内，从而使解决方案在优化的 Python 或 C++ 中可以接受。

 ## 边缘情况

 关键的边缘情况是所有元素都为零时。 在这种情况下，DP 永远不会扩展到初始状态之外。 用于输入`n=3, x=7, a=[0,0,0]`, dp 仍然`{7}`整个过程，最终的答案是`|7 - 7| = 0`，正确表明没有不平衡变化。 

另一个边缘情况是当偏移量为零并且只有一个项目时。 用于输入`n=1, x=0, a=[5]`, dp 演化自`{0}`到`{0,5}`，并且最佳分割显然在 0 和 5 之间，产生不平衡 5。DP 正确捕获了这两种状态，因为它从正确的初始条件开始。 

最后一个微妙的情况是当大值聚集在总和范围的上限附近时。 由于 DP 每次迭代都使用完整副本，因此每个项目的转换保持隔离，从而防止在同一步骤中重复使用。 即使多个组合可以通过不同路径达到相同的总和，这也可以确保正确性。
