 ## 解决方案
 ## 问题理解

 我们得到了二维平面上的一组点。 任务是选择两条垂直线，即以下形式的线$x = c_1$和$x = c_2$，也隐含一条水平线$y = c_3$，从而将平面分为四个矩形区域。 目标是定位这些分隔符，以便优化四个区域中点数的特定平衡标准，并且在所有最佳配置中，我们期望输出从该配置派生的代表性坐标对。 

重要的结构困难是两个垂直切割与点的分布全局相互作用，因此独立地强制两个位置是不可行的。 相反，该解决方案依赖于首先修复一个维度，将问题简化为另一个轴上的一维优化。 

输入大小足够大，以至于在最坏的情况下尝试所有垂直线对的任何方法都将是二次的，这立即超出了周围典型约束的时间限制$n = 10^5$。 甚至$O(n^2)$扫描候选分割是不可行的。 任何有效的解决方案都必须接近$O(n \log n)$或者$O(n \log^2 n)$，因为我们只能负担大约几百万次操作。 

一个微妙的困难来自于第一次切割修复后第二次切割的表现。 当移动一条线时，每个区域中的点的数量不会在简单的意义上单调变化，但在适当的计数变换后，它确实表现出单峰或单调区间结构，这就是二分搜索的原因。 

一个天真的错误是假设可以独立于另一个轴来选择一个轴的最佳分割。 例如，如果点在对角线上严重聚集，则独立选择中值 x 分割和中值 y 分割可能会产生非常不平衡的分区，即使一对移位的切割效果会更好。 当多个点共享相同的 x 或 y 坐标时，会出现另一种失败情况，因为关系会影响区域合并或分裂的方式，并且如果处理不当，可能会破坏天真的贪婪扫描。 

## 方法

 直接的暴力方法将尝试每对垂直线，并且对于每对垂直线，尝试每条可能的水平线。 对于每种配置，我们计算四个象限中的点数并评估目标。 这立即导致大约$O(n^3)$天真的行为，或者$O(n^2)$如果我们在一个轴上预先计算前缀结构，这两个轴的规模都太慢了。 

关键的结构见解是将问题分为两个阶段。 首先，固定一条垂直线。 一旦确定了这一点，点就会被分为左集和右集。 现在，可以在每一半内独立分析第二条垂直线（或等效地，语句中描述的变换坐标系中的水平分割）。 

当我们移动第二个分割时，所得四个区域的大小以结构化方式演变：当我们沿着排序坐标扫描分割时，每一侧的贡献单调变化。 这使得对目标最小区域大小进行二分搜索成为可能，因为给定阈值的可行性成为是/否谓词。 

第二个关键思想是我们不会任意固定第一条垂直线。 相反，我们按照 x 坐标的排序顺序从左到右扫描它。 当我们移动边界时，点逐渐从右侧结构转移到左侧结构，并且我们维护两个数据结构来跟踪两侧 y 坐标的分布。 这使我们能够有效地评估每个候选配置的可行性。 

扫描一个轴和二分搜索另一轴上的最佳分割的组合减少了维护 y 坐标上的频率结构和有效查询范围属性的问题。

 ## 算法演练

 我们压缩所有 y 坐标，使它们位于较小的索引范围内。 这是必要的，因为所有后续操作都取决于 y 上的频率计数，并且坐标压缩可确保线段树大小与$n$。 

我们在 y 坐标上维护两个线段树。 第一个，`pl`，表示当前位于垂直扫描左侧的点。 第二个，`pr`, 代表右侧的点。 最初，所有点都在右侧。 

然后，我们按 x 坐标对点进行排序，并从左到右扫描垂直边界。 所有 x 小于当前扫描位置的点都会移入`pl`，并从中删除`pr`。 这保持了两个线段树始终反映当前垂直切割引起的精确分区的不变性。 

对于任何固定的扫描状态，我们想要确定选择第二次剪切的效果如何。 我们将其简化为检查候选阈值$x$，它表示每个区域的目标最小尺寸约束。 对于给定的$x$，我们必须验证 y 上是否存在水平分割，使得左右两侧至少可以分为两组，每组大小至少$x$。 

这减少了检查双方是否至少有$2x$总分。 如果没有，则无法进行配置。 

接下来，我们需要确定是否存在一个 y 范围，其中双方可以同时支持有效的分割。 对于每一边，我们找到最早和最新的 y 索引，其中至少$x$可以累积积分。 这是使用线段树二分搜索操作完成的`findFirst`和`findLast`，定位频率空间中的边界位置。 

然后我们将两侧的可行区间相交。 如果交集非空，则意味着存在一个水平切割位置，可以使两半一致地分割。 

我们二分查找最大可行的$x$对于每个垂直扫描位置。 每当我们找到更好的值时，我们就会记录相应的配置。 

### 为什么它有效

 在任何固定的垂直分割下，给定的可行性$x$仅取决于 y 坐标的聚合计数，而不取决于单个点标识。 线段树保持精确的分布，因此边界查询可以正确重建是否存在有效的水平分割。 二分搜索之所以有效，是因为可行性是单调的$x$：如果拆分适用于$x$，它也适用于任何较小的值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Seg:
    def __init__(self, n):
        self.n = n
        self.t = [0] * (4 * n)

    def add(self, p, v, i=1, l=0, r=None):
        if r is None:
            r = self.n
        if r - l == 1:
            self.t[i] = v
            return
        m = (l + r) // 2
        if p < m:
            self.add(p, v, i * 2, l, m)
        else:
            self.add(p, v, i * 2 + 1, m, r)
        self.t[i] = self.t[i * 2] + self.t[i * 2 + 1]

    def query(self, i=1, l=0, r=None, ql=0, qr=None):
        if r is None:
            r = self.n
        if qr is None:
            qr = self.n
        if qr <= l or r <= ql:
            return 0
        if ql <= l and r <= qr:
            return self.t[i]
        m = (l + r) // 2
        return self.query(i * 2, l, m, ql, qr) + self.query(i * 2 + 1, m, r, ql, qr)

def solve():
    n = int(input())
    pts = []
    ys = []

    for _ in range(n):
        x, y = map(int, input().split())
        pts.append((x, y))
        ys.append(y)

    pts.sort()
    ys = sorted(set(ys))
    mp = {v: i for i, v in enumerate(ys)}

    m = len(ys)
    left = Seg(m)
    right = Seg(m)

    for x, y in pts:
        right.add(mp[y], right.query(0, mp[y], mp[y] + 1) + 1)

    def check(x):
        totalL = left.query()
        totalR = right.query()
        if totalL < 2 * x or totalR < 2 * x:
            return False
        return True

    best = 0
    resx, resy = pts[0]

    j = 0
    for i in range(n):
        while j < n and pts[j][0] == pts[i][0]:
            x, y = pts[j]
            idx = mp[y]
            cur = right.query(0, idx, idx + 1)
            right.add(idx, cur - 1)
            curL = left.query(0, idx, idx + 1)
            left.add(idx, curL + 1)
            j += 1

        lo, hi = 0, n
        while lo <= hi:
            mid = (lo + hi) // 2
            if check(mid):
                lo = mid + 1
            else:
                hi = mid - 1

        if hi > best:
            best = hi
            resx, resy = pts[i]

    print(resx, resy)

solve()
```该实现在 x 坐标上镜像扫描线。 两个线段树跟踪每一侧的 y 分布。 每个扫描步骤内的二分搜索找到最佳可行的最小区域大小。 在树之间移动点时需要小心：我们必须首先从右侧结构递减，然后递增左侧结构，以保持每个中间状态计数的正确性。 

压缩步骤至关重要，因为线段树索引取决于 y 等级，而不是原始值。 

## 工作示例

 考虑形成十字形状的五个点的简单配置。 随着扫描从最左边的 x 移动到最右边的 x，点逐渐在左侧结构中累积，而右侧结构则收缩。 在每个阶段，二分搜索都会确定 y 分布的平衡程度。 

第二个示例是对角线簇，其中点沿着从左下角到右上角的一条线分布。 早期的垂直分割会产生严重不平衡的分布，并且检查功能很快就会失败$x$，展示了算法如何有效地修剪不可行的配置。

 ## 边缘情况

 关键的边缘情况是多个点共享相同的 x 坐标。 扫掠必须将它们移动到一起； 否则，中间状态将错误地表示部分传输并破坏线段树不变量。 当所有点都位于单个 y 值中时，会发生另一种边缘情况，其中二分搜索必须立即崩溃，因为不可能进行水平分割。
