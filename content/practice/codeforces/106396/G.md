 ## 解决方案
 ## 问题理解

 我们正在研究标记位置的随机过程`0`到`n - 1`。 在每一步，系统使用固定的转移规则在这些位置上重新分配概率质量，因此状态始终是`n`职位。 

该问题不是询问单个长随机游走，而是有效地重复应用此转换`k`从所有概率都集中在位置的简并分布开始的时间`0`。 在这些之后`k`迭代中，我们会被问到多个查询：对于给定的位置`x`，该过程处于的概率是多少`x`？ 

核心困难在于转变不是任意的。 它有一个非常具体的结构，其中下一个状态在位置`i`仅取决于先前状态的前缀结构，并且归一化涉及除以“剩余”位置的数量。 这创建了累积分布样式更新而不是局部卷积。 

从官方解决方案隐含的约束来看，`n`可以很大，并且两者`k`和`q`也足够大，以至于天真地模拟每个查询的过程是不可行的。 直接模拟需要重新计算完整的`n`-长度概率向量`k`次，从而导致成本`O(nk)`每次测试，当两个参数都达到数万或更多的量级时，这个值就太大了。 

关键的微妙之处在于，随着过程的重复，这种转变迅速将概率质量集中在较高指数附近。 根据经验，经过大约 40 到 50 个步骤后，分布在数值上变得稳定，并且额外的转换不再对其产生有意义的改变。 这表明对固定分布的强烈收缩行为。 

一个幼稚的错误是假设独立性或局部性，例如单独处理每个位置或尝试将其建模为具有稀疏转换的简单马尔可夫链。 但这会失败，因为每个步骤都涉及跨后缀片段的全局标准化。 另一种常见的错误方法是独立地重新计算每个查询，这忽略了所有查询都依赖于相同的最终分布。 

## 方法

 暴力解释很简单：维护一个数组`dp[i]`表示位置的概率`i`。 每次转换都会构建一个新数组`ndp`其中每个位置根据转移规则接收来自所有有效的先前贡献的概率质量。 由于每次迭代都会扫描所有`n`位置并更新另一个`n`职位、一步成本`O(n)`。 

重复此操作`k`步骤给出`O(nk)`复杂。 如果两者都`n`和`k`很大，这很快就会超出可行的限制，特别是因为每个查询在预处理后仍然需要 O(1) 查找。 

关键的观察结果是该过程收敛得非常快。 这种转变以增加对更高指数的集中度的方式反复重新分配概率。 经过少量迭代后，分布变得稳定，达到浮点精度。 这意味着我们实际上并不需要所有`k`步骤； 我们只需要前几十步，之后状态就不再发生显着变化。 

所以而不是迭代`k`次，我们将其限制在大约`min(k, 50)`。 这将算法转变为对阵列进行固定的少量线性扫描，总预处理成本为`O(50n)`，这实际上是线性的。 

这背后更深层次的结构是，过渡可以用累积和来重写。 每一步构建`ndp[i]`使用`ndp[i - 1]`，这意味着计算本质上是基于前缀的。 这允许一次计算每次迭代，而无需嵌套循环。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nk) | O(nk) | O(n) | 太慢了|
 | 截断的DP+前缀更新| O(n·分钟(k, 50)) | O(n) | 已接受 |

 ## 算法演练

 我们维护一个概率数组`dp`在哪里`dp[i]`表示处于该位置的概率`i`经过多次转变之后。 

1. 初始化`dp`所有质量都处于该位置`0`。 这对进程的起始状态进行编码。 
2. 将转换次数限制为`k = min(k, 50)`。 原因是，在大约 50 次迭代之后，分布不再以任何有意义的方式发生变化，因此进一步的计算只会浪费时间，而不会影响结果。 
3. 重复转换`k`次。 每次迭代都会构造一个新数组`ndp`从目前的`dp`。 
4. 对于每个索引`i`从`0`到`n - 1`，计算对的贡献`ndp[i]`使用前缀累积：

 公式的建立使得`ndp[i]`取决于当前值`dp[i]`按标准化因子缩放`1 / (n - i)`加上累计贡献`ndp[i - 1]`。 

这种结构确保概率质量以受控累积方式向前流动，而不是在每个位置独立流动。 
5. 填充后`ndp`， 代替`dp`和`ndp`并继续进行下一次迭代。 
6.完成所有迭代后，通过直接输出来回答每个查询`dp[x]`。 

### 为什么它有效

 这种转变保留了总概率，并以单调累积方式反复将质量重新分配到更高的指数。 每次迭代都可以被视为对概率向量应用线性算子。 该算子在实践中对于这种特定结构是收缩的，这意味着重复应用会快速驱动系统趋向定点分布。 一旦矢量稳定，算子的进一步应用使其在数值精度范围内保持不变，因此以 50 步截断可为所有实际输入产生正确的限制分布。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, q = map(int, input().split())
    k = min(50, k)

    dp = [0.0] * n
    dp[0] = 1.0

    for _ in range(k):
        ndp = [0.0] * n
        for i in range(n):
            ndp[i] = dp[i] / (n - i)
            if i > 0:
                ndp[i] += ndp[i - 1]
        dp = ndp

    for _ in range(q):
        x = int(input()) - 1
        print(f"{dp[x]:.10f}")

if __name__ == "__main__":
    solve()
```该实现完全遵循所描述的迭代前缀构造。 内循环构建`ndp`在一次传递中，每个条目重用先前计算的前缀和`ndp[i - 1]`，消除了对嵌套循环的任何需要。 

一个微妙的细节是划分`(n - i)`。 这必须以浮点计算以保持概率准确性，并且必须在添加前缀项之前应用它，因为`ndp[i]`取决于部分构建的状态。 

预处理后查询处理很简单，因为每个答案都是直接数组查找。

 ## 边缘情况

 一个关键的边缘情况是当`n = 1`。 该数组只有一个位置，因此每次转换都必须完全保留索引处的概率`0`。 该算法处理这个问题是因为循环运行在单个索引上，并且`n - i`总是`1`，所以不会出现除法问题，并且`dp[0]`遗迹`1.0`自始至终。 

另一个边缘情况是`k = 0`。 在这种情况下，不会发生任何转换，并且应直接返回初始分布。 自从`k`被限制并且循环被完全跳过，输出正确地保留`[1, 0, 0, ...]`。 

对于较大的`k`，50 处的截断是最重要的行为。 如果`k`非常大，一个简单的实现会尝试模拟所有步骤，但上限版本确保分布已经收敛。 该过程仍然会产生一致的输出，因为额外的转换不再以有意义的方式改变状态。
