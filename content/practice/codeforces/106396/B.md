 ## 解决方案
 ## 问题理解

 我们得到一个带权无向图。 每条边连接两个顶点并带有成本。 任务是选择一组将所有顶点连接在一起的边，形成单个连接结构，同时最大化所选边权重的总和。 如果不可能连接所有顶点，则答案必须报告为不可能。 

看待这个问题的另一种方式是我们想要一个具有最大总边权重的生成树。 生成树是连接每个顶点且不包含环的边的子集。 在所有这些有效结构中，我们想要权重总和最大的一个。 

输入大小足够大，任何尝试枚举边子集或重复重新计算连接的解决方案都会太慢。 由于图形的典型 Codeforces 限制，二次或指数方法立即被排除。 甚至一个$O(n^2)$当顶点数量很大并且图很稠密时，该方法会太慢，因为边的数量可能会增长到$O(n^2)$在最坏的情况下。 

约束驱动的一个关键含义是我们需要一种近线性或对数的每次操作方法来进行连接检查。 这直接表明了不相交的集合并集结构，因为它支持快速并集和查找操作。 

当图表断开连接时，会出现微妙的边缘情况。 例如，如果我们有 4 个节点并且只有边 (1,2) 和 (3,4)，则无法形成单个生成树。 天真的贪婪选择可能仍然选择两条边并输出总和，但正确的输出是 -1，因为结构未完全连接。 

另一种极端情况是同一对顶点之间存在多条边。 粗心的实现可能会同等对待它们，但正确的算法必须独立考虑它们，因为只有最佳组合才能形成最佳生成树。 

## 方法

 蛮力的想法是尝试每个边子集，检查它是否形成生成树，并计算其总权重。 检查连通性可以使用 BFS 或 DFS 来完成，并验证是否确实存在$n-1$边缘确保非循环性。 这种方法是正确的，因为它直接测试每个有效的候选结构。 然而，边缘子集的数量为$2^m$，以及每次有效性检查成本$O(n + m)$，使得总复杂度$O(2^m \cdot (n + m))$，即使对于中等小的图也是不可行的。 

关键的结构观察是我们正在解决最大生成树问题。 问题归结为精确选择$n-1$连接所有顶点同时最大化总重量的边。 这与经典的最小生成树问题相同，只是我们反转顺序以最大化而不是最小化。 

克鲁斯卡尔算法提供了所需的结构。 我们不是按权重升序对边进行排序，而是按降序对它们进行排序。 然后，我们迭代边并使用不相交的并集来仅接受连接先前断开的组件的边。 每个接受的边合并两个分量并贡献总重量。 这种贪婪的选择之所以有效，是因为连接两个已连接组件的任何边都会创建一个循环，并且无法改进生成树结构，而应优先考虑最重的可用边以最大化总和。 

最后，如果我们没有准确地使用$n-1$边，图是断开的并且不存在生成树。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(2^m \cdot (n + m))$|$O(n + m)$| 太慢了|
 | 克鲁斯卡尔 (DSU) |$O(m \log m)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 读取顶点和边的数量，然后将所有边存储为包含端点和权重的三元组。 这为按权重排序准备了数据，这是贪婪策略的核心。 
2. 按权重降序对所有边进行排序。 原因是我们要首先考虑较重的边，以便它们最有可能包含在生成树中。 
3. 初始化一个不相交的并集结构，其中每个顶点都从​​其自己的组件开始。 这种结构将使我们能够快速确定添加边缘是否会连接两个单独的组件或创建一个循环。 
4. 按排序顺序迭代边。 对于每条边，使用 DSU 查找操作检查其端点是否属于不同的组件。 如果它们不同，我们将它们合并并将边缘权重添加到答案中。 如果它们已经在同一个组件中，我们会跳过它，因为它会形成一个循环。 
5. 维护剩余组件数量的计数器。 每次成功的合并都会将组件数量减少一个。 
6. 处理完所有边后，检查是否只剩下一个连通分量。 如果不是，则说明该图不完全连通，无法形成生成树。 
7. 如果图形是连通的，则输出累加的权重和。 

### 为什么它有效

 在任何时刻，该算法都会维护一个连接组件的森林。 每个选定的边是当时连接两个不同组件的最大可能边。 这确保了在不破坏连接的情况下，任何选定的边都不能被更重的有效替代边替换。 由于从未引入循环，因此该结构始终保持森林状态，一旦所有顶点都连接起来，选定的边就会形成具有最大可能总权重的生成树。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

def solve():
    n, m = map(int, input().split())
    edges = []

    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((u - 1, v - 1, w))

    edges.sort(key=lambda x: x[2], reverse=True)

    dsu = DSU(n)
    total = 0
    used = 0

    for u, v, w in edges:
        if dsu.union(u, v):
            total += w
            used += 1

    if used != n - 1:
        print(-1)
    else:
        print(total)

if __name__ == "__main__":
    solve()
```DSU结构用于有效地维护连接的组件。 路径压缩可确保每次操作的平摊时间接近恒定，即使对于大型图也能保持算法快速。 按降序排序可确保首先考虑较重的边缘，这对于最大化总重量至关重要。 

变量`used`跟踪成功包含的边数。 有效的生成树$n$节点必须准确包含$n-1$边，所以这是最终的正确性检查。 

## 工作示例

 考虑一个具有 4 个节点和边的小图：(1-2, 10)、(2-3, 5)、(3-4, 7)、(1-4, 1)。 

按降序排序后，边变为：(1-2, 10)、(3-4, 7)、(2-3, 5)、(1-4, 1)。 

| 步骤| 边缘| 之前的组件 | 行动| 总计 |
 | --- | --- | --- | --- | --- |
 | 1 | 1-2 (10) | {1}{2}{3}{4} | 合并| 10 | 10
 | 2 | 3-4 (7) | 3-4 (7) | {1,2}{3}{4} | 合并| 17 | 17
 | 3 | 2-3 (5) | 2-3 (5) | {1,2}{3,4} | 合并| 22 | 22
 | 4 | 1-4 (1) | 1-4 (1) | {1,2,3,4} | 跳过| 22 | 22

 该轨迹显示了算法如何构建生成树，同时始终选择最高的可用连接边。 

现在考虑一个断开连接的图：3 个节点，只有边 (1-2, 5)。 

| 步骤| 边缘 | 之前的组件 | 行动| 总计 |
 | --- | --- | --- | --- | --- |
 | 1 | 1-2 (5) | 1-2 (5) | {1}{2}{3} | 合并| 5 |

 处理完毕后，节点3仍处于隔离状态，因此结果无效，输出变为-1。 

这表明最终的连接检查至关重要。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(m \log m)$| 排序边缘占主导地位，DSU 操作几乎恒定摊销 |
 | 空间|$O(n + m)$| DSU 阵列和边缘列表的存储 |

 复杂性完全符合大型图的典型约束，因为排序对于多达数十万条边来说是有效的，并且 DSU 操作几乎线性扩展。

 ## 边缘情况

 对于单个顶点，DSU 从一个组件开始，不需要边。 该算法永远不会有意义地进入边缘循环，并且`used`保持为零。 自从$n-1 = 0$，满足条件，答案为 0，符合空生成树的正确定义。 

对于断开连接的图，例如节点 1-2 连接且节点 3 隔离，该算法仅合并可达组件。 DSU 以两个组件结束，因此`used`变为 1，同时$n-1 = 2$。 最终检查正确地拒绝结果并输出-1，匹配跨越所有顶点的不可能性。
