 ## 解决方案
 ## 问题理解

 堆是通过按照固定的物理顺序落下球来建造的。 下一个球总是进入能够支撑它的最高空位置，并且当多个位置具有相同高度时，安东内拉可以选择其中任何一个。 每个球都有一种颜色，在整个构建完成后，我们会看到相连的一组具有相同颜色的接触球。 任务是在可以产生的每个可能的堆中找到最大的这样的组。 

输入给出球的数量，然后按照球插入的确切顺序给出球的颜色。 输出是一个整数：最后一堆中单色连通分量的最大可能大小。 

150 个球的限制足够小，我们可以对有意义的选择的实际数量进行指数计算，但不能对球的数量进行指数计算。 对每一个可能的位置进行搜索都会产生巨大的分支因素。 关键是物理过程严重限制了可能的形状。 该堆只能有大约 17 行，因为第 17 个三角形数已经是 153，所以独立的左/右决策的数量很少。 

一些边缘情况很容易被忽略。 

当只有一个球时，别无选择，答案总是 1。 

输入示例：```
1
7
```输出是：```
1
```粗心的实现可能会在检查完整行是否存在之前尝试构建行结构，从而导致索引不正确。 

另一种情况是所有球都具有相同的颜色。 无论建造时做出什么选择，整个桩都是相连的。 

输入示例：```
5
1 1 1 1 1
```输出是：```
5
```仅检查同一行内相邻球的解决方案会错过行之间的对角线接触。 

最后一个棘手的情况是最后一行不完整。 例如：```
4
1 5 5 1
```输出是：```
2
```三个球后，第一个三角形就完成了。 第四个球必须延伸到底排，两个可能的侧面形成镜像布局。 最后一个球接触了前面的两个球，但它不能通过未完成一侧不存在的位置连接。 将最后一行视为完整的行会创建错误的连接。 

## 方法

 每当存在两个同等高的位置时，对所有可能选择的直接模拟就会分支。 对于一堆 150 个球来说，这意味着要探索太多的排列方式。 蛮力的想法是正确的，因为每个生成的堆都可以被模拟和检查，但可能性的数量随着选择的数量呈指数增长。 

有用的观察来自于观察几何形状。 最高的可用位置总是逐行填满堆。 这些球从上到下形成长度为 1、2、3 等的行。 一旦一行开始被填充，唯一的自由是新行是向左还是向右增长。 可能的行数很少，因此独立决策的数量也很少。 

150 个球最多可以占据 17 行，因为前 17 行长度之和为 153。我们可以枚举这些行的每种可能的方向。 对于每个方向，我们构建相应的球接触图并运行图遍历以找到包含单一颜色的最大连通分量。 

布局数量最多约为2^17，即13.1万个左右。 每个布局只有 150 个球，因此检查所有布局很实用。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(布局数量 × N²)，布局数量呈指数 | O(N²) | 如果每个球都独立处理选择，那就太慢了 |
 | 最佳| O(2^R × N²)，其中 R 是行数 | O(N²) | 已接受 |

 ## 算法演练

 1. 将插入序列拆分为长度为 1、2、3 等的行。 第一行包含添加到该行的最后一个球，因为行是从下向上填充的，因此我们在创建几何布局时颠倒了构造顺序。 
2. 枚举行的每个可能的左/右方向。 一行可以被镜像，这些选择描述了插入过程可以创建的每个可能的堆。 最多有 17 行，因此枚举很小。 
3. 对于每个方向，将每个球放置在三角形网格上的整数坐标处。 当它们的坐标相差适当的量时，同一行中的连续位置接触，并且相邻行中的位置对角接触。 
4. 构建碰球邻接图。 如果两个球在此图中共享一条边，则它们是相连的。 
5. 对每个未访问过的球进行深度优先搜索。 在遍历过程中，仅继续穿过与起始球颜色相同的球。 该遍历的大小是一种可能的簇大小。 
6. 保留在所有生成的方向上找到的最大簇大小。 

为什么它有效：

 插入规则不允许任意稳定的桩。 最高可用槽位规则强制将堆填成三角形行。 唯一剩下的自由是当有两个等高选择时每行向哪一侧延伸。 因此，枚举所有行方向涵盖了每个可能的堆。 对于任何固定桩，图遍历恰好访问每个单色连通分量中的球，因此为该桩找到的最大值是正确的。 取所有可能的桩中的最大值即可给出所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    colors = list(map(int, input().split()))

    rows = []
    idx = n - 1
    length = 1
    while idx >= 0:
        take = min(length, idx + 1)
        row = list(range(idx - take + 1, idx + 1))
        rows.append(row)
        idx -= take
        length += 1

    rows.reverse()

    row_count = len(rows)
    answer = 0

    # Coordinates for rows from top to bottom.
    base_positions = []
    for r, row in enumerate(rows):
        start = -r
        base_positions.append([start + 2 * i for i in range(len(row))])

    for mask in range(1 << row_count):
        coords = [None] * n
        positions = []
        for r, row in enumerate(rows):
            cur = base_positions[r][:]
            if (mask >> r) & 1:
                cur.reverse()
            positions.append(cur)
            for ball, x in zip(row, cur):
                coords[ball] = (x, r)

        graph = [[] for _ in range(n)]
        pos_to_ball = {}
        for i, p in enumerate(coords):
            pos_to_ball[p] = i

        directions = [(2, 0), (-2, 0), (1, 1), (-1, 1), (1, -1), (-1, -1)]
        for i, (x, y) in enumerate(coords):
            for dx, dy in directions:
                j = pos_to_ball.get((x + dx, y + dy))
                if j is not None:
                    graph[i].append(j)

        visited = [False] * n
        for i in range(n):
            if not visited[i]:
                color = colors[i]
                stack = [i]
                visited[i] = True
                size = 0
                while stack:
                    u = stack.pop()
                    size += 1
                    for v in graph[u]:
                        if not visited[v] and colors[v] == color:
                            visited[v] = True
                            stack.append(v)
                answer = max(answer, size)

    print(answer)

if __name__ == "__main__":
    solve()
```代码的第一部分重建行结构。 输入顺序是插入顺序，而几何行最容易从最后插入的球向后构建。 该循环重复地从序列中删除最后一个完整的行长度。 

枚举循环尝试每行的每种可能的方向。 这些行以可能的反转存储，表示将该行延伸到另一侧的选择。 

坐标的分配使得触摸球在六个相邻三角网格方向之一上有所不同。 从坐标到球索引的字典让我们可以构建图表，而无需搜索所有球对。 

深度优先搜索仅计算与起始球颜色相同的球。 访问的数组在整个遍历过程中共享，因为另一种颜色的球不能属于同一簇。 所有布局中的最大值就是最终结果。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(2^R × N²) | O(2^R × N²) | 最多有 17 种行方向选择，每种布局都需要构建一个图并遍历它 |
 | 空间| O(N²) | 邻接图仅包含每个球的恒定数量的边，但表示形式受 N² | 限制。 

最大可能的行数很小，因为 150 个球几乎填满了一个有 17 行的三角形。 因此，枚举大小约为 131,000 个布局，每个布局仅处理 150 个球，这非常合适。

 ## 边缘情况

 对于单个球：```
1
7
```行分解创建包含一个球的一行。 没有接触对，因此遍历返回一对。 算法输出`1`。 

对于全部相等的桩：```
5
1 1 1 1 1
```每个生成的方向在接触图的每个顶点上都具有相同的颜色。 从任何起始球开始的遍历到达所有五个球，给出最大可能的簇大小`5`。 

对于部分行的情况：```
4
1 5 5 1
```分解创建具有三个位置的底行和具有一个位置的顶行。 枚举尝试了放置第四个球的两种方法。 在每种情况下，图构建仅添加现有球之间的真实接触，因此来自缺失位置的假想邻居无法加入集群。 最大的单色分量仍然是尺寸`2`。
