 ## 解决方案
 ## 问题理解

 任务是恢复蚂蚁识别程序将分配的下一个标识符。 输入描述了识别系统当前看到的标识符。 有些值是有效的标识符，而格式错误的值（例如负数或远远超出有用范围的数字）必须被忽略。 在剩下的非负标识符中，我们需要找到没有出现的从零开始的最小整数。 

输入最多可以包含一百万个值，每个值可能包含近一百位数字。 大数字长度排除了对固定大小整数类型语言中每个值依赖正常整数解析的可能性。 更重要的是，对于一百万个条目，任何重复扫描整个集合或测试许多候选答案的解决方案都会执行太多的工作。 我们需要一种输入值数量接近线性的方法。 

关于答案范围的关键观察来自标识符的数量。 如果有 N 个输入值，则最小的缺失非负整数永远不会大于 N。即使从 0 到 N-1 的每个数字都出现，也只有 N 个，因此 N 是第一个可能的缺失值。 这意味着大于 N 的值不会影响答案，可以立即丢弃。 

一些边缘情况很容易被错误处理。 当没有值时，集合为空，答案为零。```
Input:
0
```正确的输出是`0`。 从一而不是从零开始搜索的解决方案在这里会失败。 

第二种情况涉及看起来是数字但不能是有效标识符的被忽略的值。```
Input:
5
-3
999999999999999999999999
abc
0
1
```正确的输出是`2`。 只有零和一是相关的。 存储每个解析值或假设每个输入都适合普通整数的粗心解决方案可能会浪费内存或在解析时失败。 

前导零是错误的另一个可能来源。```
Input:
3
000
001
3
```正确的输出是`2`。 价值观`000`和`001`代表零和一。 将它们视为不同的字符串会错误地认为零和一不存在。 

## 方法

 直接的解决方案是重复检查候选号码。 我们可以从零开始，测试它是否出现在输入集中，然后继续使用一、二等等，直到找到缺失值。 这是正确的，因为第一个缺席的候选者正是所需的标识符。 对于哈希集，每次查找的时间复杂度预计为 O(1)，但该方法仍然需要一种方法来存储所有有效值并重复检查候选值。 在最坏的情况下，输入包含从 0 到 N-1 的每个数字，因此我们在读取 N 个值后执行大约 N 次查找。 这对于散列来说是可以接受的，但是扫描输入数组中每个候选者的简单实现将需要大约 N2 操作，这大约是对 100 万个条目进行 1012 次检查。 

更好的方法来自于限制唯一重要的值。 由于答案最多为 N，因此我们只需要知道存在 0 到 N 范围内的哪些数字即可。 我们可以创建一个大小为 N+1 的布尔数组。 在读取每个输入值时，我们忽略负数和大于 N 的值。对于有用范围内的值，我们标记相应的位置。 处理完所有输入后，第一个未标记的位置是丢失的标识符。 

困难在于输入数字最多可以有 100 位数字，因此将所有内容都转换为整数是不必要的，而且可能不安全。 相反，我们将文本表示与 N 进行比较。删除符号和前导零后，只有当值的长度最多为 N 的长度，或者具有相同的长度并且按字典顺序不大于 N 时，该值才可用。 

暴力破解之所以有效，是因为它直接检查缺失值的定义，但它会浪费精力处理超出答案范围的值以及重复搜索。 观察到答案受 N 限制，我们可以将问题简化为标记可能标识符的小前缀。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| --- | --- |
 | 蛮力 | O(N²) | O(N) | 太慢了|
 | 最佳 | O(N) | O(N) | 已接受 |

 ## 算法演练

 1.读取标识符个数并创建数组`present`有 N+1 个位置。 位置`i`表示是否是标识符`i`出现。 N 需要额外的位置，因为答案可能等于 N。 
2. 将每个标识符作为字符串读取，而不是立即将其转换为整数。 从非负值中删除前导零，以便同一数字的不同文本形式变得相同。 
3. 忽略负数或归一化值大于 N 的值。此类值无法更改最小缺失标识符，因为保证答案最多为 N。 
4. 标记每个剩余值`present`大批。 这准确地记录了最终搜索所需的信息。 
5. 扫描`present`从索引零向上并输出第一个值为 false 的索引。 该索引是当前未分配的最小标识符。 

这样做的原因是每个可能是答案的标识符都在数组中表示。 超出此范围的值不能作为答案，因此忽略它们不会丢失任何信息。 

为什么它有效：

 处理完所有输入后，`present[x]`当标识符恰好为 true 时`x`出现在每个的相关输入值中`x`介于零和 N 之间。考虑第一个索引`k`这仍然是错误的。 每个较小的标识符都被标记，因此从零到每个值`k-1`存在。 标识符`k`不存在，使其成为最小的缺失标识符。 如果没有丢失更小的值，则扫描无法提前停止，因此生成的答案始终是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def normalize_number(s):
    if s[0] == '-':
        rest = s[1:].lstrip('0')
        if rest == '':
            return "0"
        return None
    s = s.lstrip('0')
    return s if s else "0"

def solve():
    line = input().strip()
    if not line:
        return
    n = int(line)

    present = [False] * (n + 1)
    limit = str(n)

    for _ in range(n):
        s = input().strip()
        value = normalize_number(s)
        if value is None:
            continue

        if len(value) < len(limit) or (len(value) == len(limit) and value <= limit):
            x = int(value)
            present[x] = True

    for i, exists in enumerate(present):
        if not exists:
            print(i)
            return

if __name__ == "__main__":
    solve()
```这`normalize_number`函数可以处理大型输入格式，而不需要任意精度的算术。 它删除前导零，正确处理零，并拒绝真正的负值。 

对比`n`发生在打电话之前`int`。 这是重要的优化，因为除非已证明 100 位数字小到足以产生影响，否则不应转换该值。 一旦字符串长度和字典顺序比较表明该值最多为 N，则转换是安全的，因为该值适合布尔数组的范围。 

这`present`数组正好存储 N+1 个可能的答案。 最后的循环从零开始，这避免了忘记零是有效标识符的常见差一错误。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N) | 每个标识符被读取并处理一次，最终扫描最多检查 N+1 个位置。 |
 | 空间| O(N) | 布尔数组存储从 0 到 N 的每个可能答案是否存在。 |

 该算法对每个输入行执行少量恒定的工作，并避免处理不必要的大整数。 对于一百万个标识符，线性内存和时间要求符合预期限制。

 ## 边缘情况

 对于空输入列表，该算法创建一个仅包含标识符零状态的数组。 扫描立即发现零没有标记并打印`0`，匹配最小可用标识符的定义。 

对于非常大的数字，请考虑：```
5
0
1
999999999999999999999999999999
-2
3
```归一化后的大值位数多于 N，因此在转换之前将其丢弃。 负值也被丢弃。 标记的标识符是零、一和三，因此扫描返回二。 

对于前导零，请考虑：```
4
000
001
003
4
```这些值被标准化为零、一、三和四。 数组位置零、一、三和四被标记，留下位置二作为第一个缺失的标识符。 输出是`2`。 

对于重复的标识符，请考虑：```
5
2
2
0
1
1
```标识符“two”被标记两次，但布尔数组仅存储存在性，而不存储频率。 存在位置 0、1 和 2，因此算法正确返回 3。
