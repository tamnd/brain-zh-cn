 # 问题理解

 我们得到了观察到的鸟类运动的有向图。 真实飞行的原始图是未知的，但是每一条真实的边都必须出现在观察到的图中，而一些观察到的边可能是代表更长真实路径的捷径。 

对于固定的树T，我们需要找到每棵树a，使得边a→T保证是真正的边。 仅当观察图内从 a 到 T 的每个可能路径都使用该精确边时，才能保证观察到的边 a → T。 

约束允许最多 100000 个节点和 100000 个边。 单独检查每个传入边缘的路径的解决方案很容易变得二次，这太慢了。 我们需要用线性或近线性遍历来处理图。 

关键的边缘情况是由替代路线引起的。 直接进入 T 是不够的。 例如：```
3 3 2
0 1
0 2
1 2
```答案是：```
1
1
```节点 0 有一条到 2 的边，但路径 0 → 1 → 2 避开了该边，因此 0 无效。 

另一种情况是循环：```
3 3 2
0 2
0 1
1 2
```答案仍然只是节点 1。如果另一个传出边最终可以到达 T，则直接边并不重要。 

# 方法

 直接的方法是检查 T 的每个前驱 a 并删除边 a → T。如果 T 仍然可以从 a 到达，则不能保证该边。 这是正确的，因为定义询问是否存在替代路径。 然而，在最坏的情况下，对每个传入边进行图遍历的成本为 O(M(N + M))，这对于 100000 个顶点来说是不可能的。 

重要的观察结果是，从 a 到 T 的每一条替代路径都必须以一条与 a → T 不同的离开 a 的边开始。我们不需要单独测试每条边。 我们只需要知道哪些顶点可以到达T。 

从T开始运行一次反向图遍历。如果一个顶点能够到达原图中的T，则该顶点被标记。 对于一条入边 a → T，如果 a 有另一条出边 a → x，其中 x 被标记且 x 不是 T，则存在另一条从 a 到 T 的路径，因此不保证该边。 否则，从 a 到达 T 的唯一可能途径是通过 a → T。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(M(N+M)) | O(N+M) | 太慢了|
 | 最佳 | O(N+M) | O(N+M) | 已接受 |

 # 算法演练

 1. 构建反向图。 为每个原始边 a → b 添加一条反向边 b → a。 从该图中的T开始遍历，正好访问原图中能到达T的节点。 
2. 在反向图上从 T 开始运行 DFS 或 BFS，并标记所有可达节点。 这些是唯一可以出现在以 T 结尾的路径中的节点。 
3. 在读取输入时存储每个节点的所有出边，因为稍后我们需要检查候选前驱是否有另一条通往 T 的路由。 
4. 对于每条边 a → T，检查 a 的所有出边。 如果存在一条边 a→x，其中 x 与 T 不同，并且 x 标记为能够到达 T，则 a 无需使用 a→T 就可以到达 T，因此将其丢弃。 
5. 对所有剩余的前驱进行排序并打印它们。 

为何有效：从 a 到 T 的避开边 a → T 的路径必须以其他出边 a → x 开始。 在第一次移动之后，路径的剩余部分正是从 x 到 T 的路径。反向遍历精确地标记了存在此类后缀路径的那些 x 值。 因此，该算法准确地拒绝具有替代路径的边缘并准确地接受有保证的真实边缘。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, t = map(int, input().split())

    graph = [[] for _ in range(n)]
    rev = [[] for _ in range(n)]
    incoming = []

    for _ in range(m):
        a, b = map(int, input().split())
        graph[a].append(b)
        rev[b].append(a)
        if b == t:
            incoming.append(a)

    reachable = [False] * n
    stack = [t]
    reachable[t] = True

    while stack:
        v = stack.pop()
        for u in rev[v]:
            if not reachable[u]:
                reachable[u] = True
                stack.append(u)

    ans = []
    for a in incoming:
        ok = True
        for x in graph[a]:
            if x != t and reachable[x]:
                ok = False
                break
        if ok:
            ans.append(a)

    ans.sort()
    print(len(ans))
    for x in ans:
        print(x)

if __name__ == "__main__":
    solve()
```第一次遍历适用于反转图，因为可达性方向是反转的。 逆图中从T到达节点x就意味着原来有一条从x到T的路径。 

最后的循环仅检查已经具有到 T 的直接边的顶点。这已经足够了，因为每个答案都必须是 T 的前驱。对于每个这样的顶点，只有当另一个传出边通向最终可以返回到 T 的顶点时，另一条传出边才是危险的。 

不使用递归，因为 Python 递归深度对于具有 100000 个顶点的图来说太小。 迭代堆栈避免了这个问题。

 # 边缘情况

 直接传入的边沿仍然可能无效。 在：```
3 3 2
0 2
0 1
1 2
```反向遍历将每个节点标记为能够到达2。在检查节点0时，发现边0→1，并标记节点1，因此算法拒绝0。 

循环内的节点可能仍然有效。 在第二个示例中，节点 4 有一条到 2 的边，但它的其他出边不存在，因此从 4 到 2 的每条路径都必须使用 4 → 2。即使图中其他地方包含循环，算法也会接受它。
