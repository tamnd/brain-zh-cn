 ## 解决方案
 ## 问题理解

 生成器从固定的 40 位值开始，反复将其转换为下一个值。 该变换将当前值、删除最低 20 位所获得的值和一个常数相加，然后仅保留最低 40 位。 任务是先看第一个`N`生成值并计算其中有多少个是偶数。 

输入值`N`几乎可以大到`2^63`，因此一次模拟一个元素的序列是不可能的。 即使是非常快的循环也需要数十亿年才能获得最大的输入。 我们需要找到一个重复结构并计算完整的重复次数，而不是生成每个请求的元素。 

有用的观察是我们不需要整个 40 位状态。 该问题只询问最低位，因为该位决定数字是否为偶数。 为了计算下一个最低位，我们只需要当前数字的最低 21 位。 该位移出`>> 20`正好是第 20 位，并且该位包含在这 21 位中。 

粗心的解决方案可能会在多个边界上失败。 例如，使用输入`0`，序列不包含值，所以答案是`0`。 始终处理初始状态的解决方案将错误地输出`1`。 

用于输入`1`， 仅有的`S(0)`被计算在内。 自从`0x600DCAFE`以偶数十六进制数字结尾，正确答案是`1`。 在计数之前应用转换的解决方案会意外计数`S(1)`反而。 

对于非常大的输入，例如`500000000`，直接模拟所有生成的值是不切实际的。 正确的输出是`250065867`，这需要使用简化状态的循环，而不是迭代每个生成的数字。 

## 方法

 蛮力方法直接遵循定义。 它存储当前 40 位值、检查其奇偶校验、应用递归并重复。 这是正确的，因为它完全访问了问题所要求的值。 然而，对于`N = 2^63 - 1`，它需要大约`9.22 * 10^18`的转变，远远超出了极限。 

递归的结构给了我们一个更小的状态空间。 当前值的奇偶校验取决于位零。 下一个值的位零取决于当前值的位零和位二十，因为移位项仅来自上部部分。 因此，低21位形成一个独立的系统。 

由于请求的序列长度巨大，暴力方法会失败。 低 21 位独立演化的观察结果减少了可能状态的数量`2^40`只到`2^21`。 我们可以生成这个小序列直到它重复，计算一个周期中偶数状态的数量，并使用算术跳过完整的周期。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N) | O(1) | O(1) | 太慢了 |
 | 21 位状态的循环检测 | O(2^21) | O(2^21) | O(2^21) | O(2^21) | 已接受 |

 ## 算法演练

 1. 仅用最低 21 位替换原来的 40 位状态。 如果当前的还原状态是`x`，下一个简化状态计算为`(x + (x >> 20) + 12345) mod 2^21`。 这是可行的，因为来自高 19 位的影响接下来的低 21 位的唯一信息是位 20。 
2. 生成简化状态，从`0x600DCAFE & ((1 << 21) - 1)`。 存储每个状态出现的第一个位置。 继续直到某个状态重复，因为从该点开始序列是周期性的。 
3. 将生成的序列拆分为不重复前缀和重复循环。 计算两个部分内的偶数状态。 
4.如果`N`小于前缀长度，直接从前缀应答。 否则，添加前缀贡献，使用整数除法跳过尽可能多的完整循环，并处理剩余的循环元素。 

工作原理：约简状态恰好包含确定未来约简状态和每个生成数字的奇偶性所需的信息。 一旦缩减状态第二次出现，所有后续缩减状态都会以相同的顺序重复。 该算法对前缀进行一次计数，并在数学上考虑每个完整的重复，因此第一个中的每个`N`值仅贡献一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MASK = (1 << 21) - 1
START = 0x600DCAFE & MASK
C = 12345

def build_cycle():
    seen = {}
    order = []
    x = START

    while x not in seen:
        seen[x] = len(order)
        order.append(x)
        x = (x + (x >> 20) + C) & MASK

    cycle_start = seen[x]
    return order, cycle_start

order, cycle_start = build_cycle()

prefix_even = [0] * (len(order) + 1)
for i, x in enumerate(order):
    prefix_even[i + 1] = prefix_even[i] + (1 if (x & 1) == 0 else 0)

cycle = order[cycle_start:]
cycle_even = sum(1 for x in cycle if (x & 1) == 0)

def solve(n):
    if n <= cycle_start:
        return prefix_even[n]

    ans = prefix_even[cycle_start]
    n -= cycle_start

    ans += (n // len(cycle)) * cycle_even
    n %= len(cycle)

    for i in range(n):
        if (cycle[i] & 1) == 0:
            ans += 1

    return ans

n = int(input())
print(solve(n))
```这些常数定义了简化的生成器。`MASK`精确保留最低 21 位，并且`START`丢弃初始 40 位值的不相关高位。`build_cycle`执行唯一的大型模拟。 最多`2^21`可能会出现不同的状态，因此循环是有界的。 字典记录每个状态的第一次出现，从而可以立即识别重复的片段。 

前缀数组存储偶数状态的累积计数。 这避免了为每个查询重新扫描非循环部分。 循环计数是单独存储的，因为可以通过除法跳过完整的重复。 

过渡使用`& MASK`而不是模运算。 由于模数是 2 的幂，因此保留最低 21 位是完全等价的，可以避免不必要的工作。

 ## 边缘情况

 用于输入`0`，算法进入第一个分支，因为`N`小于循环前缀长度。 返回索引零处的前缀数组值，即`0`。 不计算生成的状态。 

用于输入`1`，算法返回`prefix_even[1]`。 起始还原态是偶数，所以答案是`1`。 在计数之前不执行转换，这避免了差一错误。 

对于非常大的输入，算法从不尝试生成所有请求的值。 检测到循环后，去除不重复的前缀，将剩余长度除以循环长度，并乘以一个循环中偶数状态的数量。 剩下的几个状态是单独检查的，所以最终的计数仍然与第一个状态完全对应`N`生成的值。
