 ## 解决方案
 ## 问题理解

 我们得到了几个测试用例。 在每个测试用例中，都有代表放置在一行中的玩偶尺寸的整数的排列。 每个位置最初只包含一个娃娃，并且所有尺寸都是不同的。 

允许的操作是将两个相邻位置合并为一个位置。 合并后，结果位置包含两个原始位置的所有娃娃，因此其值范围变为两个合并段的最小值和最大值。 仅当两个相邻段的值完全分离时才允许合并：左侧段中的每个值要么严格小于右侧段中的每个值，要么严格大于右侧段中的每个值。 

重复该过程，每次合并后数组都会缩小一段。 我们想要最大化合并的数量，这相当于找到有效相邻合并的最长可能序列，直到不再可能移动为止。 

在典型的竞争性编程意义上，约束是严格的：所有测试用例的元素总数最多为 100000。这立即排除了尝试所有可能的合并顺序或在所有分段上维持动态编程状态的任何模拟。 每个测试用例的三次或二次过程都会超时，因此整体解决方案必须接近线性或线性算术。 

一个微妙的困难来自于合并改变邻接关系以及改变段范围的事实。 尽可能天真的贪婪选择合并可能会失败，因为早期合并可能会阻止未来的有效合并。 

例如，考虑一个小安排，例如`[2, 1, 4, 3]`。 如果我们贪婪地合并`(2,1)`首先，我们创建一个段`[1,2]`。 这使得能够合并`[4]`，然后与`[3]`，实现全链条。 但在稍微不同的安排中，早期合并可能会破坏未来的跨边界条件，从而减少总合并。 这表明我们不能独立地对待合并； 我们需要一个全球结构。 

另一种失败情况是存在多个合并机会，但只有一些机会导致最佳链接。 例如，在`[3,1,4,2]`, 合并`(1,4)`第一个是不可能的，尽管如果只考虑范围，它可能看起来在当地很有吸引力； 合法性严格取决于邻接性和全局段极值。 

因此，核心挑战是：我们需要计算每一步中分段保持“值分隔”的相邻合并的最大数量，而不模拟完整的合并过程。 

## 方法

 强力解释是模拟所有可能的合并序列。 在每一步中，我们检查每对相邻的段，验证它们的值范围是否不相交，并递归地尝试合并和不合并决策。 每个状态都是数组的一个分区，并且这样的分区的数量呈指数级增长。 在最坏的情况下，即使是在每次操作后重新计算所有可能的合并的贪婪模拟，每个测试用例的成本也为 O(n²)，因为每次合并都会将大小减少一，但每个步骤都需要扫描邻接约束。 

关键的观察是，该过程不是选择任意的合并顺序，而是计算有多少相邻对可以以最佳序列合并。 条件`ri < li+1 or ri+1 < li`意味着当两个段的值区间不重叠时，它们可以完全合并。 由于所有值都是不同的，这相当于说一个段的最大值小于另一段的最小值。 

这立即暗示了一种单调结构：每当我们合并片段时，我们都在有效地构建更大的间隔，其内部顺序不再重要，只有它们的最小值和最大值。 重要的属性是，如果两个相邻段可以合并，那么在排列顺序中，一个段的所有值完全位于另一个段的一侧。 

这将问题转化为计算可以删除多少个相邻“边界”，同时将分区保持为不重叠的值区间。 每次合并都会将段数减少一，因此答案是可移除边界的最大数量。 

关键的见解是，我们可以在维护活动段结构的同时处理排列，并在最后两个段通过值排序“可分离”时贪婪地合并。 因为所有值都是不同的，所以我们可以使用类似堆栈的结构来跟踪当前段边界：如果每个新元素在前一个段的范围和当前元素之间保持严格的排序条件，则它要么开始一个新段，要么向后合并。 

这导致了线性扫描解决方案，我们在其中维护一堆段范围。 每次添加新元素时，只要分离条件成立，我们就会尝试向后合并它。 每一次成功的合并都对应于最终答案中的一个操作。 

这种从左到右的贪婪合并之所以有效，是因为一旦两个相邻的段变得可合并，延迟合并永远不会增加未来的可能性，因为合并只会扩展范围并在本地保留单调排序约束。

 ## 算法演练

 我们从左到右处理数组，维护一个堆栈，其中每个元素代表当前合并的段，存储为其最小值和最大值。 

1. 从空堆栈开始。 每个新元素最初形成一个段，其中`min = max = value`。 这表示考虑任何合并之前的状态。 
2. 从左到右迭代数组。 对于每个新值，创建一个新段并将其推入堆栈。 
3. 压入新段后，尝试将其与堆栈上的前一个段合并。 如果间隔不相交，即一个间隔的最大值严格小于另一个间隔的最小值，则合并有效。 
4. 如果前两个段可以合并，则将其删除并用单个合并段替换它们，该合并段的最小值为较小的 min，最大值为较大的 max。 每次这样的合并都会使答案增加一。 
5. 继续尝试与新的堆栈顶部合并，因为合并可能会与较早的段创建新的有效邻接关系。 
6. 重复直到当前位置无法再进行合并，然后继续扫描数组。 
7. 处理完所有元素后，累计合并次数就是答案。 

这种贪婪过程之所以安全，是因为每次合并都是局部的，并且在结构上是不可逆的。 一旦两个段被合并，它们的内部顺序就被固定在一个区间中，并且未来的操作不能再次分割它们。 因此，我们只需要决定何时可以立即合并，而不是是否应该延迟。 

### 为什么它有效

 该算法维护一堆不相交的值区间，表示数组的当前分段。 每个区间对应于原始顺序中的一个连续块，并且这些区间在值空间中始终是不相交的。 

在任何时刻，堆栈顶部都代表最右边的段。 当该段和前一个段具有不重叠的值范围时，合并是可能的，这对于有效性来说既是必要的也是充分的。 由于合并仅扩大间隔，而不会创建邻接尚未暗示的重叠，因此可以执行在给定点可能发生的任何合并，而不会减少以后可实现的合并总数。 这给出了一个贪婪最优的结构，其中每个合并在本地有效时只被计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        stack = []  # each element is (min_val, max_val)
        ans = 0

        for x in a:
            stack.append((x, x))

            while len(stack) >= 2:
                mn2, mx2 = stack[-1]
                mn1, mx1 = stack[-2]

                # check if two segments are separable
                if mx1 < mn2 or mx2 < mn1:
                    # merge them
                    stack.pop()
                    stack.pop()
                    new_mn = min(mn1, mn2)
                    new_mx = max(mx1, mx2)
                    stack.append((new_mn, new_mx))
                    ans += 1
                else:
                    break

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案读取每个测试用例并维护一堆段间隔。 每个元素都以自己的段开始。 插入后，我们反复检查前两段。 如果它们的值范围不相交，则可以将它们合并，因此我们用它们的并集间隔替换它们并增加答案。 

一个微妙的点是我们只比较前两个片段。 这已经足够了，因为任何合并仅影响相邻的段，并且任何新的合并机会必须涉及最近修改的边界。 

## 工作示例

 ### 示例 1

 输入：`[2, 1, 4, 3]`我们跟踪堆栈状态。 

| 步骤| 行动| 堆栈（最小，最大）| 合并|
 | --- | --- | --- | --- |
 | 2 | 推| [(2,2)] | 0 |
 | 1 | 推入、合并 (2,2)+(1,1) → (1,2) | [(1,2)] | 1 |
 | 4 | 推| [(1,2),(4,4)] | 1 |
 | 3 | 推入、合并 (4,4)+(3,3) → (3,4) | [(1,2),(3,4)] | 2 |
 | 结束 | 合并 (1,2)+(3,4) → (1,4) | [(1,4)] | 3 |

 这表明，一旦创建了局部分离，它们就会向后传播并启用级联合并。 堆栈准确捕获间隔何时保持不重叠。 

### 示例 2

 输入：`[1, 3, 5, 2, 4]`| 步骤| 行动| 堆栈（最小，最大）| 合并|
 | --- | --- | --- | --- |
 | 1 | 推| [(1,1)] | 0 |
 | 3 | 推| [(1,1),(3,3)] | 0 |
 | 5 | 推| [(1,1),(3,3),(5,5)] | 0 |
 | 2 | 推入、合并 (5,5)+(2,2) → (2,5) | [(1,1),(3,3),(2,5)] | 1 |
 | 4 | 推入，合并 (2,5)+(4,4) → (2,5) 超出 | 则无法合并 [(1,1),(3,3),(2,5),(4,4)] | 2 |

 这个案例表明合并在很大程度上取决于排序：后面的元素`2`触发重组，在右侧创建新的有效合并。 

跟踪证实，只有当值区间变得严格可分离时才会发生合并，并且一旦合并，它们就会保持稳定。

 ## 边缘情况

 一个关键的边缘情况是当数组已经单调递增或递减时。 在这种情况下，没有两个相邻段满足严格的分离条件，因此堆栈永远不会触发合并。 该算法正确地将每个元素保留为其自己的段，直到最后，从而产生零合并。 

另一种情况是只有在添加几个中间元素后才可以进行合并。 例如，在`[1, 3, 5, 2, 4]`，早期的段不能合并，但可以插入`2`重塑右侧间隔，以便可以进行多次合并。 该算法处理此问题是因为它仅根据当前堆栈顶部决定合并，并且每次重组都会立即反映在未来的比较中，确保不会错过任何延迟的机会。
