 ## 解决方案
 ## 问题理解

 我们在原点放置一个雷达，每个岛屿就变成了从原点出发的一个方向，用它的极角来表示。 雷达不会一次扫描固定扇区，而是可以自由旋转，并且在任何选定的方向上，它都会覆盖以某个方向 θ 为中心、宽度为 α 的圆形角度窗口。 在那一刻，它看到了方向位于该角度间隔内的所有岛屿。 

要求比单次扫描更强。 我们必须选择 α，以便无论我们如何旋转雷达，至少 k 个岛屿始终位于其可见角度窗口内。 换句话说，单位圆上每个可能的长度为α的圆弧必须至少包含n个方向角中的k个。 

因此，几何图形消失为纯粹的角度问题：我们获取所有点，将它们转换为 [0, 2π) 中的角度，对它们进行排序，并求出最小弧长 α，使得任何长度 α 的弧至少覆盖圆上的 k 个点。 

约束很大：每个测试文件最多 2 × 10^5 个点，最多 10^4 个测试用例。 这排除了每个测试用例的任何二次方，甚至每个测试用例的 O(n log n) 也必须仔细对待，因为总 n 跨测试是有限的。 预期的解决方案总体上必须基本上是线性的或线性算术的。 

打破天真的推理的微妙之处是循环。 角度以 2π 环绕，因此除非我们显式复制数组，否则间隔不是线性段。 另一个微妙的问题是，答案不一定与现有观点一致。 最坏情况的弧由点之间的间隙定义。 

一个天真的错误是假设我们只需要从每个点开始检查窗口而不处理环绕复制。 例如，如果点聚集在 0 和 2π 附近，则最佳弧可能会跨越边界。 忽略这一点会产生太小的答案。 

## 方法

 使用 atan2 将每个岛映射到距原点的一个角度。 一旦排序，问题就变成了一个圆覆盖约束：每个长度为 α 的区间必须包含至少 k 个点。 

蛮力方法尝试每一个可能的起始角度并计算有多少点落入长度为 α 的弧中。 对于固定的 α，我们可以围绕圆滑动一个窗口并检查任何窗口中的最小计数。 如果直接实现的话，这将是 O(n^2)，因为每个起始位置可能需要向前扫描，并且尝试通过二分搜索调整 α 仍然会使每个检查保持 O(n)。 对于最多 2 × 10^5 点，这太慢了。 

关键的观察是最坏情况窗口始终由循环排序中的 k 个连续点确定。 如果我们希望每条长度为α的弧至少包含k个点，那么等效地，必须控制允许k个点进入的最大间隙。 更准确地说，考虑圆上的任意 k 个连续点。 包含它们的最小弧由该循环顺序中第一个和第 k 个之间的角距离确定。 如果任何这样的弧超过 α，则存在大小为 α 的窗口无法捕获 k 个点的位置。 

因此，答案由循环排序角度的所有 k 长度窗口的最大值决定。 我们计算所有角度，对它们进行排序，通过添加+2π来复制数组，并计算角度[i]和角度[i + k − 1]之间的最大差。 该值就是在最坏配置下能够覆盖k个点的最小弧长，这正是所需要的α。 

这将问题简化为排序后的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解窗口检查 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 排序 + 在圆上滑动 k 窗口 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

1. 使用 atan2(y, x) 将每个点 (x, y) 转换为角度。 这将所有岛屿映射到圆形坐标系上，其中顺序对应于原点周围的方向。 
2. 将角度归一化到 [0, 2π) 范围内。 这确保了循环比较的一致性。 
3. 按升序对所有角度进行排序。 这给出了循环顺序的线性表示（环绕除外）。 
4. 通过将每个角度加上 2π 创建一个扩展数组。 这种复制对圆形包裹进行建模，以便每个圆形线段都成为线性空间中的连续线段。 此步骤是必要的，因为窗口可能会跨越 2π 边界。 
5. 对于原始范围内的每个索引 i，将 k 个连续点的跨度计算为 Angle[i + k − 1] − Angles[i]。 这表示覆盖从 i 开始的 k 个点的最小弧。 
6. 跟踪所有 i 的最大此类跨度。 该最大值是可能的最小 α，保证长度 α 的窗口不会错过 k 个点。 
7. 输出该最大值。 

步骤 5 背后的原因是，任何包含 k 个点的弧都必须包含按排序顺序的某个 k 个连续点的集合。 因此，最坏情况所需的弧完全由连续的k元组决定。 

### 为什么它有效

 修复包含 k 个点的圆上的任意弧。 如果我们按排序的角度顺序列出所有点，则该弧内的 k 个点按该顺序形成一个连续的子序列，可能会环绕末尾。 复制后，该子序列成为 k 个连续元素的正常段。 覆盖它们的最小弧的长度恰好是该线段端点之间的差。 因此，每个可行的 α 必须至少是该线段长度的最大值，并且选择等于该最大值的 α 可以保证没有弧可以避免包含 k 个点。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, k = map(int, input().split())
        angles = []

        for _ in range(n):
            x, y = map(int, input().split())
            ang = math.atan2(y, x)
            if ang < 0:
                ang += 2 * math.pi
            angles.append(ang)

        angles.sort()

        # duplicate for circular wrap
        ext = angles + [a + 2 * math.pi for a in angles]

        ans = 0.0
        for i in range(n):
            j = i + k - 1
            ans = max(ans, ext[j] - ext[i])

        out.append(f"{ans:.10f}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```核心计算完全在于将点转换为角度并分析排序顺序。 扩展 2π 至关重要，否则穿过最大角度和最小角度之间边界的窗口将被错过。 k 点上的滑动窗口确保我们只评估与实际紧密配置相对应的候选者。 

输出格式必须保持足够的精度，因为所需的容差为 1e-6。

 ## 边缘情况

 对于 k = 1，每个弧必须始终包含单个所需点，但由于雷达窗口可以在任何位置居中，因此唯一安全的 α 是 2π。 该算法可以处理此问题，因为在考虑换行时，重复数组中相同连续点之间的最大跨度变为 2π。 

对于 k = n，我们实际上要求的是该集合的完整角直径。 最大 k 窗口跨度成为考虑包裹后最大角度和最小角度之间的差值，相当于整圆减去最大间隙。 

对于聚集在小区域中的点，连续的 k 个跨度很小，算法自然会返回一个小的 α，因为所有 k 个连续的差异都很小。 

对于最紧 k 组跨越 0 弧度的环绕配置，复制可确保该段仍表示为连续窗口，并且计算的跨度可以正确捕获它，而无需特殊的大小写。
