 ## 解决方案
 ## 问题理解

 我们从左到右扫描苹果的高度。 第一个苹果总是被采摘的。 之后，只有当苹果的高度严格大于最近采摘的苹果的高度时，才会采摘苹果。 因此，所选取的高度形成前缀最大值的严格递增序列。 

每个查询都是独立的。 它只改变一个位置`p`从原来的高度`h[p]`到`q`，然后询问在结果数组中将采摘多少个苹果。 在下一次查询之前恢复原始数组。 该问题和官方竞赛解决方案将其描述为维护修改位置两侧所需的信息。 

的价值观`n`和`m`都可以达到`100000`，并且最多可以有十个测试用例。 每个查询的直接模拟最多需要`10^10`当每个查询几乎扫描整个数组时，在一个测试用例中进行数组检查。 这远远超出了 2 秒限制所能支持的范围。 我们需要接近线性或`O(n log n)`，然后是每个查询的大致对数工作量。 

第一个微妙的情况是当替换值不大于位置之前已经看到的最佳高度时`p`。 例如，考虑```
1
3 1
1 5 6
2 3
```修改后的数组为`[1, 3, 6]`，所以答案是`3`。 粗心的解决方案可能总是会计算修改后的苹果，因为它已被明确更改，但是`3`不高于之前选取的高度`1`在这个例子中它实际上是，所以它被选中。 一个更具启发性的案例是```
1
3 1
1 5 6
2 1
```修改后的数组为`[1, 1, 6]`，答案是`2`。 苹果在位置`2`等于先前选取的高度，因此严格比较会拒绝它。 将条件视为`>=`会错误地产生`3`。 

第二个微妙的情况是当修改后的苹果成为新记录时。 考虑```
1
4 1
1 2 3 4
3 10
```修改后的数组为`[1, 2, 10, 4]`，所以答案是`3`。 一次`10`被选中，后者`4`不能被挑选。 独立于原始前缀最大值计算后缀的解决方案可能会意外计算原始前缀`4`， 因为`4`是未修改数组中的一条记录。 后缀必须以新阈值开头`10`。 

第三种边界情况是对第一个位置的修改：```
1
3 1
1 2 3
1 5
```答案是`1`，因为数组变成`[5, 2, 3]`。 根本没有左前缀，因此替换值本身就是初始阈值。 任何访问职位信息的实现`p - 1`无需处理`p = 1`单独使用可能会产生无效结果。 

第四个边界情况是对最后一个位置的修改：```
1
3 1
1 2 3
3 4
```答案是`3`。 位置后没有后缀`3`，所以在决定是否位置之后`3`被选中，计算完成。 搜索从以下位置开始的更大元素的代码`p + 1`必须允许搜索范围为空。 

## 方法

 暴力解决方案只是从概念上复制原始数组，替换`h[p]`经过`q`，并扫描所有`n`职位。 在扫描过程中，我们保持最后采摘的苹果的高度，并在当前高度严格大于时增加答案。 这正是挑选规则，所以方法是正确的。 

问题在于它的成本。 一次查询需要`O(n)`时间，以及`m`查询需要`O(nm)`。 和`n = m = 100000`，最坏的情况大约是`10^10`元素检查。 即使在考虑 Python 开销之前，这也太大了几个数量级。 

暴力方法之所以有效，是因为扫描的状态只有一个数字，即迄今为止选取的最大高度。 有用的观察是改变位置`p`不能影响之前的任何决定`p`。 它仅更改后缀看到的阈值。 

对于前缀`[1, p-1]`，我们可以预先计算有多少个苹果被采摘以及最大采摘高度是多少。 此后，仅存在两种情况。 如果`q`不大于前缀最大值，位置`p`被跳过，后缀继续使用旧的前缀最大值。 如果`q`大于前缀最大值，位置`p`被选中并且后缀继续`q`作为其阈值。 

我们只剩下一个操作：给定一个从`l`和一个阈值`x`, 找到第一个高度严格大于的元素`x`。 一旦找到该元素，就可以通过预处理重用答案的其余部分。 

为了使重用成为可能，计算`nxt[i]`，右侧的第一个位置`i`其高度严格大于`h[i]`。 如果这样的职位不存在，`nxt[i]`为零。 让`dp[i]`是扫描时采摘的苹果数量`i`和治疗`h[i]`作为当前的第一阈值。 然后`dp[i] = 1 + dp[nxt[i]]`什么时候`nxt[i]`存在，并且`dp[i] = 1`否则。 这`nxt`数组可以用递减的单调堆栈在线性时间内构建。 

剩下的第一大搜索可以通过存储每个区间的最大高度的线段树来处理。 从查询位置开始，树可以丢弃每个最大值不大于阈值的区间。 当间隔可以包含有效位置时，首先向其左子节点下降，因为我们需要第一个这样的位置。 这需要`O(log n)`时间。 

这给出了线性预处理阶段和对数查询时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(nm)`|`O(1)`额外 | 太慢了|
 | 最佳|`O(n + m log n)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 预计算`prefix_count[i]`, 原始前缀中采摘的苹果数量`[1, i]`， 和`prefix_max[i]`，该前缀中最大的选取高度。 从左到右扫描时，当苹果的高度大于当前最大值时，它就会做出贡献。 这两个数组完整地描述了查询之前部分所需的所有内容`p`。 
2. 计算`nxt[i]`具有单调堆栈。 从右到左扫描位置。 当堆栈顶部的高度小于或等于`h[i]`，删除它，因为该位置永远不可能是位置上第一个严格更高的苹果`i`。 剩余的顶部是右侧的第一个位置，高度严格大于`h[i]`。 
3. 计算`dp[i]`从右到左。 如果`nxt[i]`为零，那么`i`是这个链条中最后采摘的苹果，`dp[i] = 1`。 不然采摘后`i`，下一个摘下的苹果正是`nxt[i]`， 所以`dp[i] = 1 + dp[nxt[i]]`。 
4. 在原始高度上构建线段树，存储每个节点区间的最大值。 它的目的不是直接数苹果。 它让我们找到给定索引处或之后的第一个位置，该索引的高度严格大于提供的阈值。 
5. 查询`(p, q)`，首先获取信息`[1, p-1]`。 如果`p = 1`，此前缀为空，因此使用小于每个可能高度的阈值和选取的计数为零。 否则，`prefix_count[p-1]`是已经选择的号码并且`prefix_max[p-1]`是当前阈值。 
6. 比较`q`与该前缀最大值。 如果`q`越大，位置`p`被选中，因此增加答案并将后缀阈值设置为`q`。 如果`q`小于或等于，位置`p`被跳过，后缀阈值仍然是前缀最大值。 
7.在线段树中搜索第一个位置`i > p`和`h[i] > threshold`。 如果没有这个职位，就没有后缀贡献。 否则，该位置是修改位置后采摘的第一个苹果，完整的剩余贡献是`dp[i]`。 
8.添加前缀贡献，职位可能的贡献`p`，以及后缀贡献。 由于查询是独立的，因此原始数组永远不会被修改。 

### 为什么它有效

 关键的不变量是，在扫描任何前缀后，与剩余位置相关的唯一信息是最后采摘的苹果的高度。 对于位置的查询`p`，原来的前缀没有改变，所以它的选取计数和最后选取的高度是已知的。 修改后的位置要么成为新选取的最大值，要么保持该最大值不变。 一旦后缀开始，其第一个采摘的苹果必须是严格大于此阈值的第一个元素。 选择第一个元素后，该过程与以下所示的过程完全相同`dp[i]`。 因此，每个对答案有贡献的苹果都会被计算一次，而每个无法采摘的苹果都会被排除在外。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())
        h = [0] + list(map(int, input().split()))

        # prefix_count[i] = number of picked apples in [1, i]
        # prefix_max[i] = last picked height in [1, i]
        prefix_count = [0] * (n + 1)
        prefix_max = [0] * (n + 1)

        cur_max = 0
        cur_count = 0

        for i in range(1, n + 1):
            if h[i] > cur_max:
                cur_max = h[i]
                cur_count += 1
            prefix_max[i] = cur_max
            prefix_count[i] = cur_count

        # nxt[i] = first j > i with h[j] > h[i]
        nxt = [0] * (n + 1)
        stack = []

        for i in range(n, 0, -1):
            while stack and h[stack[-1]] <= h[i]:
                stack.pop()

            if stack:
                nxt[i] = stack[-1]

            stack.append(i)

        # dp[i] = number of picked apples in the chain
        # starting by picking position i.
        dp = [0] * (n + 1)

        for i in range(n, 0, -1):
            if nxt[i] == 0:
                dp[i] = 1
            else:
                dp[i] = dp[nxt[i]] + 1

        # Segment tree for range maximum.
        size = 1
        while size < n:
            size <<= 1

        seg = [0] * (2 * size)

        for i in range(1, n + 1):
            seg[size + i - 1] = h[i]

        for i in range(size - 1, 0, -1):
            seg[i] = max(seg[i << 1], seg[i << 1 | 1])

        def first_greater(left, value):
            """First index >= left with h[index] > value, or 0."""
            if left > n:
                return 0

            def search(node, nl, nr):
                if nr < left or seg[node] <= value:
                    return 0

                if nl == nr:
                    return nl

                mid = (nl + nr) >> 1

                res = search(node << 1, nl, mid)
                if res:
                    return res

                return search(node << 1 | 1, mid + 1, nr)

            return search(1, 1, size)

        out = []

        for _ in range(m):
            p, q = map(int, input().split())

            if p == 1:
                answer = 0
                threshold = 0
            else:
                answer = prefix_count[p - 1]
                threshold = prefix_max[p - 1]

            if q > threshold:
                answer += 1
                threshold = q

            first = first_greater(p + 1, threshold)

            if first:
                answer += dp[first]

            out.append(str(answer))

        sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```前缀预处理直接对应于查询分解的第一部分。`prefix_count`记录已经选择了多少个苹果，而`prefix_max`记录传递到修改位置的阈值及其后缀。 

单调堆栈计算`nxt`在线性时间内。 比较使用`<=`， 不是`<`，因为规则要求下一个苹果严格更高。 下一个摘下的苹果不可能具有相同的高度。 

这`dp`复发是从右到左评估的，因为`dp[i]`取决于`dp[nxt[i]]`， 和`nxt[i]`总是大于`i`。 每个值最多是`n`，所以普通的Python整数就足够了。 

线段树使用从一开始的数组位置进行索引。`first_greater(left, value)`故意搜索大于或等于的索引`left`，所以查询通过`p + 1`并且永远不会意外地考虑修改后的位置本身。 

搜索首先检查左孩子。 该排序是必要的，因为可能有几个元素大于阈值，但所需的元素是第一个。 当整个子树的最大值最多达到阈值时，整个子树将被立即丢弃，因为它内部没有元素可以满足严格的不等式。 

查询永远不会改变`h`，线段树，`nxt`， 或者`dp`。 这是至关重要的，因为每个查询都描述一个单独的假设修改，而不是一系列累积修改。

 ## 边缘情况

 当`p = 1`，前缀为空。 例如，```
1
3 1
1 2 3
1 5
```算法集`answer = 0`和`threshold = 0`。 自从`5 > 0`，修改后的第一个苹果被采摘，使得门槛`5`。 后缀搜索找不到大于的值`5`，所以输出是`1`。 

什么时候`p = n`，后缀为空。 例如，```
1
3 2
1 2 3
3 4
3 1
```为了`(3,4)`，前缀贡献了两个苹果和`4 > 2`，所以位置`3`被选中，答案是`3`。 为了`(3,1)`， 位置`3`被跳过，因为`1 <= 2`，所以答案仍然是`2`。 呼叫搜索自`p + 1 = 4`立即不返回任何位置。 

当替换等于前缀最大值时，必须跳过。 例如，```
1
3 1
2 5 8
3 5
```位置前的前缀`3`有最大`5`。 由于替换也是`5`， 位置`3`没有被选中。 后缀为空，所以答案是`2`。 使用`>=`而不是`>`会错误地数出第三个苹果。 

当替换大于前缀最大值时，它成为新的阈值并完全改变哪些后缀记录存活。 例如，```
1
4 1
1 2 3 4
3 10
```前缀贡献`2`最大的苹果`2`。 替代品`10`被选中，给出当前答案`3`。 后缀包含`4`， 但`4`不大于`10`，因此不添加后缀 apple。 结果是`3`。 

当前缀已经具有较高的最大值并且替换值很小时，必须使用旧的最大值而不是替换值来搜索后缀。 例如，```
1
5 1
2 5 5 7 9
4 1
```之前的位置`4`，采摘的苹果是`2`和`5`，所以阈值是`5`。 替代品`1`被跳过。 位置后的第一个值`4`大于`5`是`9`在位置`5`， 和`dp[5] = 1`。 答案是`2 + 1 = 3`。 

单调堆栈中的相等情况同样重要。 为了```
1
4 1
5 5 5 6
1 5
```修改后的数组是`[5,5,5,6]`。 只有第一个`5`和决赛`6`被选中，所以答案是`2`。 建设时`nxt`, 位置与高度`5`必须删除较早的等高候选者，因为相等的值永远不是有效的严格更大的下一个选择。 使用`<`而不是`<=`在堆栈条件下会留下无效的等高链接并损坏 DP。
