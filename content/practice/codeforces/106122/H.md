 ## 解决方案
 # 问题理解

 仓库日志描述了工人执行的操作。 一个工作人员可能会在原始日志中出现多次，但在最终的调度中，每个工作人员必须只进入一次，并按照其原始相对顺序在内部执行所有记录的操作。 

目标是对工作人员进行重新排序，以便每个库存操作仍然可以看到它在原始日志中看到的仓库状态。 对于一个部门，如果库存操作最初发生在交货操作之前，则库存工人必须在交货工人之前停留。 如果交货发生在库存操作之前，则交货人员必须停留在库存人员之前。 在所有有效的工人订单中，我们需要工人 ID 按字典顺序排列的最小排列。 如果要求相互矛盾，则不存在排序。 

输入最多包含 100000 个工作人员以及最多两倍的日志条目。 比较每对日志条目的解决方案可能会变成二次方。 对于 200000 个操作，在 Python 中即使是 10 亿个操作也会太慢，因此我们需要线性或接近线性的图构造。 

困难在于，一个具有许多行动的部门可能意味着许多成对的约束。 例如，如果 50000 名工作人员检查某个扇区，然后 50000 名工作人员向该扇区交付数据，则朴素图包含 25 亿条边。 实现必须紧凑地表示这些约束组。 

一些边缘情况很容易被忽略。 多次出现在同一部门的工人不应该产生自我依赖。 例如：```
2 2
1 A I
1 A D
```正确的输出是：```
1 2
```这两个操作属于同一个工作人员，并且该工作人员已按照所需的内部顺序执行它们。 粗心的实现会添加从工作程序 1 到工作程序 1 的边，从而错误地报告周期。 

另一个棘手的情况是重复动作间接产生的矛盾。 考虑：```
3 6
1 A I
2 B I
3 B I
2 B D
2 A D
3 B I
```正确的输出是：```
-1
```工人 3 必须在工人 2 之前，因为 B 部门有库存，然后是交货。 工人 2 交货后，工人 3 的后续库存创建了相反的依赖关系，因此该图包含一个循环。 

# 方法

 直接的方法是构建一个有向图，其中每条边`a -> b`指工人`a`必须在工人之前进入`b`。 对于同一扇区中的每一对动作，我们可以检查它们的类型是否需要排序并添加相应的边。 这是正确的，因为每个必需的关系都被明确表示。 

问题在于边的数量。 一个部门可以包含许多库存操作，然后是许多交货操作。 每个库存工人必须先于每个送货工人，生成完整的二分图。 如果有 100,000 名工人，这可能会创建数十亿条边，并且无法存储或处理。 

关键的观察是这些约束与前缀有关。 当我们从左到右扫描一个扇区的日志时，一个库存动作只关心之前所有的交付动作，而一次交付动作也只关心之前所有的库存动作。 我们可以用代表该集合的小辅助图节点来替换大量先前的工作人员。 

对于每个部门，我们维护两条链。 一条链代表迄今为止看到的所有库存工人，另一条链代表迄今为止看到的所有送货工人。 当出现新操作时，它会连接到相反的链以强制执行所需的依赖关系，然后扩展自己的链，以便将来的操作也依赖于它。 

构建这个紧凑图后，剩下的任务是拓扑排序。 我们使用卡恩算法和真实工人的最小堆来获得字典顺序最小的答案。 辅助节点只要可用就会被处理，因为它们只是内部簿记并且不会出现在答案中。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(平方米) | O(平方米) | 太慢了 |
 | 最佳 | O(n + m) | O(n + m) | 已接受 |

 # 算法演练

 1. 创建包含工作节点和辅助节点的有向图。 每条边意味着源节点必须在目标节点之前被处理。 
2. 对于每个扇区，创建两个初始辅助节点。 一个代表该部门中已经看到的所有库存操作，另一个代表已经看到的所有交货操作。 
3. 按顺序扫描原始日志。 对于工人的库存操作`x`，从当前交付汇总节点添加一条边到`x`，因为所有早期交货都必须在此库存之前发生。 然后创建一个新的库存汇总节点，并将之前的库存汇总和`x`到它。 
4. 工人的送货动作`x`，从当前库存汇总节点添加一条边到`x`，因为所有早期库存都必须发生在此交货之前。 然后创建一个新的交付摘要节点并连接之前的交付摘要和`x`到它。 
5. 运行卡恩算法。 保留入度为零的工作堆和入度为零的辅助节点队列。 反复删除所有可能的辅助节点，然后取最小的可用worker ID。 
6. 如果少于`n`输出workers，图中包含循环，所以打印`-1`。 否则打印工人订单。 

为什么它有效：

 不变的是，每个汇总节点准确地表示在一个扇区中的当前点之前出现的一种操作类型的工作人员的集合。 当工作人员连接到汇总节点时，每个未来的相反操作都被迫等待该工作人员。 当摘要节点向前连接时，所有先前的操作都会被保留。 因此，压缩图包含与原始成对图完全相同的排序要求。 

只要存在一个有效的拓扑顺序，卡恩算法就会输出一个有效的拓扑顺序。 由于辅助节点不会出现在最终的排列中，因此在选择下一个工作节点之前对其进行处理不会改变工作节点之间的相对选择。 然后，最小堆总是选择可能最小的下一个工作者，给出字典顺序最小的有效排序。 

# Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    actions = [[] for _ in range(26)]
    for _ in range(m):
        x, c, d = input().split()
        actions[ord(c) - 65].append((int(x), d))

    graph = []
    indeg = []

    def new_node():
        graph.append([])
        indeg.append(0)
        return len(graph) - 1

    workers = [new_node() for _ in range(n)]

    def add_edge(a, b):
        graph[a].append(b)
        indeg[b] += 1

    for sector in range(26):
        inv_summary = new_node()
        del_summary = new_node()

        for x, typ in actions[sector]:
            w = workers[x - 1]

            if typ == 'I':
                add_edge(del_summary, w)

                nxt = new_node()
                add_edge(inv_summary, nxt)
                add_edge(w, nxt)
                inv_summary = nxt
            else:
                add_edge(inv_summary, w)

                nxt = new_node()
                add_edge(del_summary, nxt)
                add_edge(w, nxt)
                del_summary = nxt

    worker_ids = [i + 1 for i in range(n)]
    heap = []
    aux = []

    for i in range(len(graph)):
        if indeg[i] == 0:
            if i < n:
                heapq.heappush(heap, i)
            else:
                aux.append(i)

    ans = []
    while len(ans) < n:
        while aux:
            v = aux.pop()
            for u in graph[v]:
                indeg[u] -= 1
                if indeg[u] == 0:
                    if u < n:
                        heapq.heappush(heap, u)
                    else:
                        aux.append(u)

        if not heap:
            break

        v = heapq.heappop(heap)
        ans.append(v + 1)

        for u in graph[v]:
            indeg[u] -= 1
            if indeg[u] == 0:
                if u < n:
                    heapq.heappush(heap, u)
                else:
                    aux.append(u)

    if len(ans) != n:
        print(-1)
    else:
        print(*ans)

if __name__ == "__main__":
    solve()
```代码的第一部分创建图表。 首先创建工作节点，因此工作节点 ID 直接对应于来自`0`到`n - 1`。 随后附加辅助节点。 

这`add_edge`函数是创建边的唯一地方，因此每个依赖项都会自动更新目标入度。 

扇区扫描是二次构造的压缩版本。 摘要节点在每个操作后都会更新，这使得后面的操作依赖于每个较早的相反类型，而无需存储每一对。 

拓扑排序有两个集合。 堆存储可用的工作人员并保证字典顺序上最小的选择。 辅助列表存储可用的内部节点。 首先处理辅助节点是必要的，因为它们可能会释放在下一个工作人员选择之前应考虑的工作人员。 

# 工作示例

 样本1：```
3 5
1 A I
2 B I
3 B I
2 B D
2 A D
```重要的状态变化是：

 | 步骤| 行动| 新的依赖| 可用工人 |
 | ---| ---| ---| ---|
 | 1 | 工人 1 库存 A | 1 必须先于未来 A 交付 | 1 |
 | 2 | 工人 2 库存 B | 2 必须先于未来 B 交付 | 1, 2 |
 | 3 | 工人 3 库存 B | 3 必须先于未来 B 交付 | 1、2、3 |
 | 4 | 工人2送货B | 2 取决于之前的 B 库存 | 1, 3 |
 | 5 | 工人2交货A | 2 取决于工人 1 | 3 |

 只要有可能，就会选择最小的可用工人。 结果是：```
1 3 2
```这表明该算法不需要选择参与最近操作的工作人员。 它仅遵循依赖图。

# 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + m) | 由压缩表示创建的每个工作器、操作、辅助节点和边都会被处理恒定的次数。 |
 | 空间| O(n + m) | 图节点和边的数量与输入大小成线性关系。 |

 原始输入大小最多为 200000 个操作。 压缩图避免了成对约束的二次数，因此它可以轻松地满足限制。

 # 边缘情况

 对于在同一部门执行库存和交货的工人来说，该算法不会产生自我依赖性。 在输入中：```
2 2
1 A I
1 A D
```库存操作指向摘要节点，交付操作从该摘要中读取。 Worker 1 仍然可用，因此输出可以是：```
1 2
```对于具有许多相同类型动作后跟相反类型动作的扇区，该算法不会扩展所有成对关系。 例如，如果许多工人检查部门`A`许多后来交付给`A`，库存汇总节点存储整个组。 每次交付仅从该汇总节点添加一条边，同时仍强制执行每个所需的排序。 

对于矛盾的日志，压缩图仍然保留循环。 在第二个示例中，库存和交货摘要创建了与显式图相同的两个相反的依赖关系。 卡恩的算法最终没有可用的工人，而一些工人仍然存在，这正确地识别了不可能的时间表。
