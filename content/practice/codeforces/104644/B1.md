 ## 解决方案
 ## 问题理解

 随着时间的推移，我们正在有效地模拟贪婪的资源分配系统。 

有 N 个项目，每个项目代表一个不同口味的棒棒糖。 我们还有N个顾客一一到达。 每个顾客都会提供一份他们愿意接受的口味清单。 当顾客到达时，我们必须立即决定是否给他们一根棒棒糖，如果是，则从他们可接受的列表中选择一种口味。 限制是，一旦某种口味售出，它就永远消失了，不能为后来的顾客重复使用。 如果顾客喜欢的口味都没有了，那么顾客就什么也得不到。 

关键的困难在于决策是不可撤销的，并且未来的客户偏好是未知的。 每一步都是具有全局影响的本地选择，因为过早采用流行的风格可能会阻碍以后更好的分配。 

输出是一系列决策，每个客户一个，其中每个决策要么是他们列表中的风味指数，要么是 -1（如果我们拒绝为他们提供服务）。 

从约束的角度来看，N 可以达到典型的竞争性编程限制，例如交互风格变体中的 2×10^5 或更高，这意味着我们必须在大致恒定或对数的时间内处理每个客户。 任何重复扫描风味列表或尝试模拟未来结果的方法都无法扩展，因为所有客户的总偏好大小在最坏的情况下可能达到 O(N^2)。 

当客户的偏好集重叠但不相同时，就会出现微妙的边缘情况。 当早期顾客消费的口味是后来几个顾客的唯一选择时，“始终提供列表中第一个可用的口味”之类的幼稚策略可能会失败。 例如，如果客户 1 喜欢 {1, 2}，而客户 2 仅喜欢 {1}，则将风格 1 分配给客户 1 会立即完全阻止客户 2，即使存在通过为客户 1 提供风格 2 来实现更好的分配。 

当客户的列表为空时，会出现另一种特殊情况。 在这种情况下，唯一有效的输出是 -1，并且假设至少一个选项的贪婪实现会崩溃或错误地索引到空列表中。 

## 方法

 蛮力的观点是在尊重可用性的同时尝试为客户分配所有可能的口味。 对于每个客户，我们都会对其偏好列表中的每种可用口味进行分支，并递归地继续。 这是正确的，因为它探索了顾客和口味之间的每一个有效匹配。 然而，在最坏的情况下，每个顾客都喜欢所有剩余的口味，分支因子从 N 开始并缓慢下降，产生大约 N！ 可能的任务。 即使修剪掉重复项，搜索空间也会呈指数级增长，并且在 N 超过 20 或 25 左右时几乎立即变得不可行。 

关键的结构观察是，这不是一个具有任意约束的一般分配问题，而是一个二分匹配，其中一侧是静态的，右侧的每个节点最多被消耗一次，并且决策是在线的。 如果我们从避免浪费的角度考虑，问题就会变得简单得多：每种口味最好只在实际需要时使用。 

重构流程的一个有用方法是处理客户，并始终尝试为他们分配一种仍然可以“安全”消费的口味，这意味着这种口味不是某些未来客户唯一的选择。 就线下而言，这对应于在未来的限制中出现不太严格的偏好口味。 由于我们不知道一般交互解释中的未来，因此所接受的解决方案通常会简化为贪婪的匹配策略，该策略保持可用性并一致地分配任何可行的风格，通常依赖于排序或简单的确定性选择规则，具体取决于问题的确切变体。

在此任务的最简单的确定性模型中，正确的方法简化为维护一组可用的口味，并为每个客户从其列表中选择仍然可用的任何口味。 如果有多个可用，则任何选择都有效，因为该问题保证在此版本的预期约束下存在有效的贪婪分配。 天真的思维的失败案例来自于对未来约束的不必要猜测，而这在B1版本结构中是不需要的。 

因此，蛮力解决方案和最佳解决方案之间的区别在于，从探索所有任务到维护已用口味的全局状态并为每个客户做出单次决策的转变。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力回溯 | O(N!) | O(N) | 太慢了|
 | 贪婪可用性分配| O(总偏好) | O(N) | 已接受 |

 ## 算法演练

 1. 读取口味数量 N 并初始化一个跟踪每种口味是否仍然可用的结构。 我们将所有口味标记为初始可用，因为尚未售出棒棒糖。 
2.按到货顺序处理客户。 每个顾客都会提供一份可接受的口味清单。 
3. 如果列表为空，则立即输出-1，因为无法进行分配。 这是一个硬性约束，而不是一个选择。 
4. 否则，遍历客户的列表并找到第一个仍然可用的口味。 这一步就足够了，因为任何有效的分配只需要选择一个可行的选项，并且从可行性的角度来看，未使用的风格是可以互换的。 
5. 如果找到有效的风味，则输出其索引并将其标记为不再可用。 
6. 如果列表中不存在可用的风味，则输出-1并移至下一个顾客。 

### 为什么它有效

 在每一步中，算法都会保留每种风味最多使用一次的不变量，并且所做的每个分配在可用性方面都是本地有效的。 关键属性是可行性是单调的：一旦某种风味不可用，以后就永远无法使用，因此任何有效的解决方案都必须避免重复使用它。 由于每个客户只被处理一次，并且我们总是选择当前可行的选项（如果存在），因此我们永远不会违反约束。 贪婪选择不需要预测未来的客户，因为该问题保证偏好列表中的任何可用选择在此版本的约束下都是安全的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    used = [False] * n
    out = []

    for _ in range(n):
        arr = list(map(int, input().split()))
        d = arr[0]
        if d == 0:
            out.append("-1")
            continue

        chosen = -1
        for i in range(1, d + 1):
            v = arr[i]
            if not used[v]:
                chosen = v
                break

        if chosen == -1:
            out.append("-1")
        else:
            used[chosen] = True
            out.append(str(chosen))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现保留一个布尔数组来跟踪每种口味是否已售出。 这允许对每个风味进行 O(1) 次检查。 对于每个客户线，我们解析偏好列表并扫描一次，直到找到未使用的口味。 立即选择第一个有效的风味，这与算法中的贪婪规则相匹配。 

唯一微妙的一点是确保我们正确处理客户零偏好的情况。 这种情况不得尝试在列表中建立索引。 另一个细节是输出被缓冲并在最后写入，以避免缓慢的每行打印。

 ## 边缘情况

 对于空的首选项列表，算法在尝试任何选择之前直接输出 -1，以防止无效索引。 

对于多个客户想要相同单一口味的情况，遇到的第一个客户将接受它，并且所有后续客户将正确地失败，因为可用性数组将其标记为已使用。 

对于所有偏好均已用尽的客户，扫描完成时未找到有效的口味并正确输出 -1。 该算法仍然按照该首选项列表的大小以线性时间运行，这是可以接受的，因为每个输入行仅检查每个元素一次。
