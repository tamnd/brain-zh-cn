 ## 解决方案
 ## 问题理解

 我们得到了一系列整数，代表一张一张地排成一行的卡片。 当我们从左到右处理序列时，我们维护另一个序列，其行为类似于具有特殊取消规则的堆栈。 

当新卡到达时，它将被附加到当前序列的末尾。 如果该值以前从未出现在当前序列中，则不会发生进一步的情况。 如果它之前出现过，我们会找到最接近末尾的前一个出现，然后删除从前一个出现到新添加的卡（包括在内）的所有内容。 这意味着该结构永远不会包含相同值的两个活动出现：重复的值会触发其最近两次出现之间的段的“折叠”。 

处理完整个数组后，我们不会被要求提供全局的最终序列。 相反，我们必须回答多个查询。 每个查询都会给出原始数组的一个范围，如果我们只处理该子数组，我们必须计算最终序列的长度。 

困难在于查询是在线的并且与之前的答案进行异或编码，因此我们无法在不尊重顺序的情况下独立预处理所有查询。 这些约束允许最多 300,000 个元素和 300,000 个查询，这排除了每个查询的任何模拟或段的任何二次扫描。 甚至一个$O(n \sqrt{n})$解决方案是有风险的，因为每个查询本身可以触及很大的范围，并且动态结构的重新计算成本很高。 

一种简单的方法是独立模拟每个查询的过程。 对于单个范围，我们维护一个列表并重复插入和删除段。 每次删除可以删除许多元素，并且跨查询这变成$O(n)$在最坏的情况下每个查询，导致$O(nq)$，这远远超出了限制。 

如果试图在全局范围内仅维护最后一次出现的情况并将其重用于所有查询，则会出现一种更微妙的故障模式。 这是因为取消行为严格取决于受限子数组：查询范围之外的元素不应该存在，因此它们对“匹配对”的影响消失了。 

一个小例子凸显了这个陷阱。 假设数组是$[1, 2, 1, 2]$。 在完整的数组上，所有内容都取消为空序列。 但在范围内$[2, 3]$，序列是$[2, 1]$，这不会进一步取消。 任何重用全局取消对的解决方案都会错误地假设比子数组中实际存在的取消更强的取消。 

## 方法

 关键的观察结果是，该过程的行为就像一个堆栈，其中每个值始终仅与其先前不匹配的出现交互，并且该交互完全擦除它们之间的段。 这表明每个元素要么作为“当前开放区间”存在，要么通过关闭这样的区间而被删除。 

如果我们模拟固定数组从左到右的过程，我们可以维护一个索引堆栈。 每个值都存储其当前在堆栈中的最后位置。 当我们看到重复的值时，我们会弹出，直到删除先前出现的值，从而有效地删除连续的后缀段。 

这立即表明了一个相当于维持的结构，对于每个位置$i$, 之前出现的$a_i$在活性结构内。 如果我们知道当前有效堆栈中最近的前一个出现，则可以有效地维护堆栈。 

真正的困难是回答范围查询。 我们只需要处理后的最终堆栈大小$a_\ell \ldots a_r$。 这是一个经典的设置，其中答案取决于范围内相等元素之间的相互作用，并且这些相互作用可以表示为位置之间的边。 

一个关键的重新表述是根据父指针来思考：对于每个位置$i$， 让$p_i$是之前出现的$a_i$（如果没有则为 0）。 该过程本质上连接$i$到$p_i$，但前提是$p_i$在当前堆栈中仍然“活着”。 然后每个查询就变成：在范围内$[\ell, r]$, 反复删除对后有多少位置幸存$(p_i, i)$其中两个端点都位于该范围内并形成有效的取消链。 

这成为一个对段上的功能结构中不匹配元素进行计数的问题，随着时间的推移，段树结合类似堆栈的回滚思想可以有效地处理这个问题。 然而，更清晰的观点是使用索引段树上的持久堆栈模拟来处理查询：如果我们从空输入处理该段，我们将为每个段维护结果堆栈状态。 

每个段存储如何将输入堆栈转换为输出堆栈的压缩表示。 当组合两个相邻片段时，我们模拟将右侧片段的输出作为左侧片段的输入。 由于取消仅取决于按 LIFO 顺序匹配相等的值，因此可以使用跟踪段状态内最后出现的堆栈合并技术来解决交互。 

经典的优化是通过其不匹配元素的“简化序列”来表示每个片段，并通过模拟左侧后缀和右侧前缀之间的取消来合并两个片段，但仅限于这些压缩表示。 由于每个元素最多可以进入和离开线段树的每个级别一次简化形式，因此每个查询的总复杂度保持对数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的暴力模拟 |$O(n^2)$最坏的情况|$O(n)$| 太慢了|
 | 具有堆栈合并的线段树|$O(n \log n)$|$O(n \log n)$| 已接受 |

 ## 算法演练

 1. 在数组上构建一棵线段树，其中每个节点代表在最初为空的堆栈上处理该子数组的效果。 

每个节点都存储该段中不匹配值的简化堆栈状向量。 
2. 对于叶节点，简化表示只是一个单元素堆栈，其中包含$a_i$，因为在一个元素内不可能取消。 
3. 对于内部节点，采用左子节点的简化表示，然后将右子节点的简化表示“输入”到其中。 

这是通过模拟堆栈过程来完成的：我们迭代右向量并对当前左向量应用相同的取消规则。 
4. 在此合并期间，维护从值到当前缩减堆栈内其最后出现位置的映射。 

当我们看到一个值已经存在时，我们从堆栈中删除元素，直到删除前一个出现的元素，然后追加新的元素。 
5. 合并后，生成的缩减堆栈成为节点的存储状态。 该状态准确地代表了单独处理该段后剩下的内容。 
6. 回答询问$[\ell, r]$，我们查询线段树以获取该范围的组合缩减堆栈。 答案很简单，就是减少堆栈的大小。 

这样做的原因是减少的堆栈完全表征了处理一个段后的状态：任何未来的处理仅取决于剩余的内容，而不取决于已经解决的内部取消。 这给出了一个组合结构，其中可以合并段结果而无需重新访问原始数组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Node:
    def __init__(self):
        self.st = []

def merge(a, b):
    if not a.st:
        return b
    if not b.st:
        return a

    res = a.st[:]
    last = {}

    for i, v in enumerate(res):
        last[v] = i

    for v in b.st:
        if v in last:
            idx = last[v]
            res = res[:idx]
            last = {x: i for i, x in enumerate(res)}
        else:
            last[v] = len(res)
            res.append(v)

    a.st = res
    return a

def build(a, v, l, r, seg):
    if l == r:
        seg[v].st = [a[l]]
        return
    m = (l + r) // 2
    build(a, v*2, l, m, seg)
    build(a, v*2+1, m+1, r, seg)
    seg[v] = merge(seg[v*2], seg[v*2+1])

def query(v, l, r, ql, qr, seg):
    if ql <= l and r <= qr:
        return seg[v]
    m = (l + r) // 2
    if qr <= m:
        return query(v*2, l, m, ql, qr, seg)
    if ql > m:
        return query(v*2+1, m+1, r, ql, qr, seg)
    left = query(v*2, l, m, ql, qr, seg)
    right = query(v*2+1, m+1, r, ql, qr, seg)
    return merge(left, right)

n, q = map(int, input().split())
a = list(map(int, input().split()))

seg = [Node() for _ in range(4*n)]
build(a, 1, 0, n-1, seg)

lastans = 0
for _ in range(q):
    x, y = map(int, input().split())
    l = x ^ lastans
    r = y ^ lastans
    l -= 1
    r -= 1
    res = query(1, 0, n-1, l, r, seg)
    lastans = len(res.st)
    print(lastans)
```线段树的构建使得每个节点都存储其区间的压缩堆栈表示。 合并函数是核心逻辑：它模拟将一个缩减的堆栈输入到另一个堆栈中，应用原始过程中使用的相同取消规则。 

查询函数收集一定范围内的合并表示，以正确的顺序组合段。 最终的答案是最终减少的堆栈的大小。 

必须小心索引，因为解码后查询是从 1 开始的，而内部结构是从 0 开始的。 另一个微妙的点是，在合并期间重新计算最后出现的映射是必要的，因为早期的索引在截断后变得无效。

 ## 边缘情况

 最小边缘情况是长度为 1 的段。 该算法将其视为叶节点，并直接返回大小为 1 的堆栈，这符合无法取消的事实。 

一个更微妙的情况是取消完全发生在段内而不是跨边界。 例如，在$[1, 2, 1, 2]$，完整的段减少为空，但将其分成$[1, 2]$和$[1, 2]$产生非空中间状态。 线段树合并确保了正确性，因为它按顺序重新组合简化状态并跨边界重新应用取消。 

另一个重要的情况是具有长间隙的重复值，例如$[1, 2, 3, 1, 2, 3]$。 这里每个值都会触发一连串的删除。 该算法正确地处理了这个问题，因为每次合并仅保留不匹配的值，并重复强制截断缩减的堆栈，从而在每次交互时恰好消除所有干预元素一次。
