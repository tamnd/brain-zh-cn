 ## 解决方案
 ## 问题理解

 我们得到一个大的无向加权图，然后是许多独立的查询。 每个查询都要求在两个给定顶点之间行驶的最便宜的方式，但有严格的限制：该路线最多允许使用三个边。 

因此，我们不要求一般的最短路径，而只允许考虑极短的行走：要么是一条直接边，要么是两条边通过恰好一个中间顶点的路径，要么是一条三条边通过恰好两个中间顶点的路径。 即使价格更便宜，更长的时间也无关紧要。 

图本身可能非常大，多达一百万个顶点和一百万个边，因此我们无法承担任何按查询的图搜索。 查询数量也高达一百万，这迫使我们采用预处理方法，所有有用的信息必须计算一次，然后在恒定时间内得到答复。 

一个关键的结构约束是该图是平面的。 实际上，这意味着稀疏性：边的数量与顶点的数量成线性关系，并且平均度保持有界。 这就是枚举短距离行走可行的隐藏原因。 

主要的边缘情况源于以下事实：最佳答案可能来自不同的路径长度，并且有时最佳路径不是唯一的。 例如，直接边缘可能很昂贵，而两条边缘路由则很便宜。 

一个小例子说明了比较所有长度的需要：

 输入：```
3 3
1 2 10
2 3 1
1 3 100
1
1 3
```正确输出：```
11
```一个简单的最短路径算法可能会找到权重为 100 的直接边缘并停止，从而错过更便宜的两条边缘路线。 更重要的是，标准的 Dijkstra 是不必要的，因为超过三条边的路径是不允许的，所以全局探索是浪费工作。 

另一个微妙的情况是同一端点之间存在多个短距离步行。 我们必须只保留所有有效行走中的最小权重。 

## 方法

 强力解决方案将独立处理每个查询。 对于每对`(s, t)`，我们可以运行有界 BFS 或 Dijkstra 搜索，最多只允许三个边。 这仍然探索邻居的邻居，以及可能的邻居的邻居。 在最坏的情况下，即使是这种有界搜索，每个查询也最多可以访问 O(m) 条边，因为该算法不知道目标位于哪里，并且可能在达到深度 3 之前广泛扩展。 对于多达一百万个查询，这变得完全不可行，导致在密集情况下大约需要 10^2 次操作。 

关键的观察结果是深度限制非常小并且是固定的。 每个有效答案都对应于三种结构形式之一的路径：单边、双边链或三边链。 这意味着我们根本不需要动态搜索。 相反，我们可以一次枚举整个图中长度最多为三的每个可能路径，计算其端点和成本，并存储每个有序对的最佳结果。 

平面性确保图足够稀疏，以便枚举所有此类短路径在实践中保持线性。 每个顶点平均只有恒定数量的邻居，因此扩展所有长度为 2 和长度为 3 的游走不会组合爆炸。 

这将问题转换为本地邻域的预处理任务，然后每个查询进行 O(1) 哈希查找。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询搜索的暴力破解 | O(q·m) | O(n + m) | 太慢了 |
 | 枚举所有 ≤3 边路径 | 预期 O(m) | O(米) | 已接受 |

 ## 算法演练

 ### 最优预处理策略

 1. 构建一个邻接列表，存储每个顶点的所有邻居以及边权重。 这提供了对本地结构的恒定时间访问，这是至关重要的，因为每个有效路径的长度最多为三。 
2. 初始化哈希图`best[(u, v)]`这将存储任何有效路径的最小成本`u`到`v`最多使用三个边。 我们存储有向对，因为即使图是无向的，路径也有方向。 
3. 插入所有单边路径。 对于每一个边缘`(u, v, w)`， 更新`best[(u, v)]`和`best[(v, u)]`有成本`w`。 这可以处理所有长度为 1 的解决方案。 
4. 通过将每条边延伸一次来枚举所有长度为 2 的路径。 对于每个顶点`u`，考虑每个邻居`v`，那么对于每个邻居`x`的`v`，我们得到一条路径`u → v → x`有成本`w(u, v) + w(v, x)`。 更新`best[(u, x)]`。 此步骤捕获所有有效的双边路由。 
5. 再次延伸以生成所有长度为 3 的路径。 对于每个长度为 2 的结构`u → v → x`, 迭代邻居`y`的`x`并更新`best[(u, y)]`有成本`w(u, v) + w(v, x) + w(x, y)`。 这完成了所有有效的三边行走。 
6. 回答每个问题`(s, t)`通过返回`best[(s, t)]`如果存在，否则输出`-1`。 

### 为什么它有效

 每个有效答案都精确对应于长度为 1、2 或 3 的游走。该算法通过迭代相邻边的所有可能序列来显式构造所有此类游走。 因为每一步都延伸一条真实的边缘，所以不会引入无效路径。 由于我们仅存储每个端点对的最小成本，因此多个重叠结构可以正确地折叠为最优值。 不可能丢失有效路径，因为中间顶点的每个可能选择都是通过邻接扩展枚举的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        adj[u].append((v, w))
        adj[v].append((u, w))
        edges.append((u, v, w))

    best = {}

    def upd(a, b, w):
        key = (a, b)
        if key not in best or w < best[key]:
            best[key] = w

    for u, v, w in edges:
        upd(u, v, w)
        upd(v, u, w)

    for u in range(1, n + 1):
        for v, w1 in adj[u]:
            for x, w2 in adj[v]:
                if x == u:
                    continue
                upd(u, x, w1 + w2)

    for u in range(1, n + 1):
        for v, w1 in adj[u]:
            for x, w2 in adj[v]:
                if x == u:
                    continue
                for y, w3 in adj[x]:
                    if y == v:
                        continue
                    upd(u, y, w1 + w2 + w3)

    q = int(input())
    out = []
    for _ in range(q):
        s, t = map(int, input().split())
        out.append(str(best.get((s, t), -1)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```邻接表是该解决方案的支柱，因为它允许一步恒定地枚举所有可到达的候选者。 这`best`字典是整个答案空间的压缩表示：它不显式存储路径，而是仅存储每个端点对的最佳成本。 

三重嵌套扩展是关键部分。 第一个循环对所有边进行编码。 第二个循环构建所有双边行走，第三个循环将它们扩展为三边行走。 小支票，如`x == u`或者`y == v`避免立即进行琐碎的回溯，否则会产生冗余状态，尽管正确性并不依赖于它们。 

所有查询答案都是简单的字典查找，这使得解决方案可以扩展到一百万个查询。

 ## 边缘情况

 比多步路径更差的直接边会被正确处理，因为初始化步骤存储所有边，但后来来自两条边和三边扩展的更新可能会被更小的值覆盖。 

例如，在一个三角形中`1-2-3`重边`1-3`，算法首先存储`(1,3)=heavy`，然后后来发现`1→2→3`并将其替换为较小的值。 这确保最终的字典始终反映所有允许的路径长度中的最佳路径长度。 

第二种边缘情况是最佳路径恰好使用三个边缘。 第三扩展层确保显式生成所有此类路径。 即使两条边前缀不是最佳的，它仍然用作构建块，因此不会跳过有效的三边解决方案。
