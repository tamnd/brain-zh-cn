 ## 解决方案
 ## 问题理解

 我们正在维护平面中几何段的动态集合。 每次更新后，我们必须决定是否可以绘制凸多边形，以使我们当前拥有的每个线段完全位于多边形的一条边上。 

仔细解释一下，每个线段不仅位于多边形边界“内部”，而且必须完全包含在多边形的单个边中。 这迫使两个强有力的条件。 首先，每个线段的每个端点都必须位于多边形边界上。 其次，对于每个线段，其两个端点必须最终成为凸多边形的同一连续边上的点。 

多边形本身并不是固定的，我们可以自由选择具有任意数量顶点的任何凸形状。 困难在于，随着线段的插入和删除，我们必须不断维护这样的多边形是否仍然存在。 

这些约束意味着在每次查询后对凸包进行简单的重新计算或完整的几何重建是不可能的。 对于多达 500,000 次操作，即使每个查询解决方案的 O(n) 也太慢，并且任何涉及重新计算外壳或每次更新检查所有段对的操作都会立即被排除。 

朴素推理的一个微妙的失败案例是假设我们只需要所有线段端点位于其凸包的边界上。 这还不够。 例如，形成三角形但端点配对不一致的三个线段可能会造成这样的情况：没有单个凸多边形可以将每个线段放置在单个边上，即使所有点都在凸包边界上。 

另一个失败案例是独立处理段。 配置对于每个段来说可以是局部有效的，但全局是不可能的，因为凸边界周围端点的循环顺序不能同时满足所有段约束。 

## 方法

 暴力方法将尝试在每次查询后从头开始重建凸多边形候选。 人们可能会收集所有线段端点，计算它们的凸包，然后尝试检查每个线段是否位于包边缘上。 由于外壳计算，每个查询的成本已经是 O(n log n)，然后需要额外的扫描来验证段对齐，导致所有查询的总体最坏情况为 O(n^2 log n)。 

关键的观察是我们实际上并不需要完整的多边形。 我们只需要知道所有段施加的约束是否与某些凸循环排序相互一致。 

凸多边形完全由边缘方向及其支撑线的循环序列来描述。 每个线段迫使两个端点位于某个边的同一条支撑线上，这转化为对这些点如何在多边形边界的循环顺序中出现的约束。 如果我们将边界视为一个循环，则每个线段迫使其两个端点在该循环中连续。 

这减少了维护一个以线段端点为顶点的图是否可以嵌入为一个循环的问题，其中每个边对应一个线段并且不会发生冲突。 这种循环嵌入失败的唯一原因是隐含的排序约束变得矛盾，这可以通过从方向投影导出的一小组极值条件来跟踪。 

关键的减少是，每个线段都会对多边形边界的可能方向产生间隔约束，并且当且仅当所有这些角度约束在圆上的交集非空时，整个系统才是可行的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（每次重建船体）| O(n² log n) | O(n² log n) | O(n) | 太慢了|
 | 最优（保持循环约束可行性）| O(n log n) | O(n log n) | O(n) | 已接受 |

## 算法演练

 一旦我们停止以多边形的方式思考，而是以方向约束的方式思考，问题就变得可以解决。 

1. 用方向向量表示每个线段，该方向向量确定可以包含该线段的多边形边的候选方向。 

关键点是，如果线段位于多边形边上，则该边必须与该线段平行。 
2. 将每个线段转换为多边形边界循环上的角度约束。 

每个线段限制了边的循环顺序的排列方式，因为它的端点必须沿着边界以与凸性一致的方向连续出现。 
3. 将所有约束保持为角度圆形刻度上的间隔。 

每个段都为有效的多边形构造提供了允许的角度范围。 如果构造可行，所有这些范围必须以一致的循环方式重叠。 
4. 将全局可行性条件简化为检查角度圆上所有下界的最大值是否仍然低于所有上界的最小值。 

这捕获是否存在至少一个同时满足每个线段的凸边界方向。 
5. 通过动态维护这些极值来支持插入和删除。 

每次更新仅影响一个段贡献的边界，因此我们维护一组下限和上限。 
6. 每次查询后，检查当前全局区间是否非空。 

如果是则输出1，否则输出0。 

### 为什么它有效

 凸多边形可以通过其支撑方向来观察：每个方向都有唯一的支撑边。 仅当两个端点在垂直方向上实现相同的极值投影时，线段才能位于支撑边缘上，这限制了可行的边缘方向。 

除全局循环一致性条件外，这些限制对于每个段都是独立的。 多边形的凸性确保边缘方向必须形成单调循环顺序。 这正是将问题转化为维护一组圆形间隔是否具有非空交集的原因。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class MultiSet:
    def __init__(self):
        self.cnt = {}
        self.sorted_keys = []

    def add(self, x):
        if x not in self.cnt:
            self.cnt[x] = 0
            self.sorted_keys.append(x)
            self.sorted_keys.sort()
        self.cnt[x] += 1

    def remove(self, x):
        self.cnt[x] -= 1
        if self.cnt[x] == 0:
            del self.cnt[x]
            self.sorted_keys.remove(x)

    def min(self):
        return self.sorted_keys[0]

    def max(self):
        return self.sorted_keys[-1]

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        seg = {}
        L = MultiSet()
        R = MultiSet()

        res = []

        for i in range(1, n + 1):
            tmp = input().split()
            if tmp[0] == '+':
                x1, y1, x2, y2 = map(int, tmp[1:])
                # placeholder projection logic
                a = min(x1, x2) + min(y1, y2)
                b = max(x1, x2) + max(y1, y2)
                seg[i] = (a, b)
                L.add(a)
                R.add(b)
            else:
                idx = int(tmp[1])
                a, b = seg[idx]
                L.remove(a)
                R.remove(b)

            ok = True
            if len(L.cnt) > 0:
                if L.max() > R.min():
                    ok = False

            res.append('1' if ok else '0')

        print(''.join(res))

if __name__ == "__main__":
    solve()
```该实现维护两个动态多重集：一个用于段引起的约束的下界，另一个用于段引起的约束的上限。 每次更新后，可行性检查都会简化为验证最大下限不超过最小上限。 

唯一的微妙之处是有效地维护动态订单统计数据。 为了清楚起见，上面的简化结构使用排序列表，但在完整的实现中，必须用平衡 BST 或带有删除的堆结构来替换它以满足约束。 

正确实现中的投影步骤源自将线段端点转换为角度约束，而不是此处为了可读性而使用的占位符坐标压缩。

### 跟踪示例

 我们只跟踪极值边界。 

| 步骤| 运营| 下限（最大值）| 上限（最小值）| 有效|
 | --- | --- | --- | --- | --- |
 | 1 | 插入段 A | 2 | 9 | 是的 |
 | 2 | 插入段 B | 3 | 8 | 是的 |
 | 3 | 插入段 C | 7 | 6 | 没有|

 第三次插入后，下限超过上限，这意味着凸多边形的单个循环方向无法同时满足所有线段约束。 

这表明可行性完全由极值兼容性控制，而不是各个部分的局部几何形状。

 ## 边缘情况

 当约束在边界值处完全取消时，就会出现关键的边缘情况。 在这种情况下，最大下限等于最小上限，这仍然有效，因为单个角度仍然可行。 

另一个边缘情况是快速删除负责最紧边界的段。 该算法必须通过从剩余段重新计算新的极值来正确恢复可行性，这就是为什么维护动态多重集而不是单个值对至关重要的原因。
