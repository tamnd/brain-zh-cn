 ## 解决方案
 ## 问题理解

 我们有一个固定的排列$p$大小的$n$，我们想将它与字典顺序早于的所有其他相同大小的排列进行比较$p$。 对于每个这样的排列$p'$，我们计算一个统计量$f(p')$，它计算一个值后面紧随其后继值的次数。 更准确地说，我们计算索引对$i < j$这样$p'_i + 1 = p'_j$，无论它们是否相邻。 

然后我们对所有排列进行分类$p'$按字典顺序小于$p$根据 的值$f(p')$，并且对于每个$k$，我们需要计算有多少个这样的排列$f(p') = k$。 

输出是所有可能值的频率分布$f(p')$在字典顺序上小于给定排列的排列中。 

主要困难在于我们不是对所有排列进行计数，而是仅对字典顺序的前缀进行计数。 这使得该问题从根本上来说是一个基于排列的前缀 DP 问题，而不是一个全局计数问题。 

约束条件$n \le 100$立即排除阶乘枚举。 甚至生成所有排列也是不可能的，因为$n!$是一个天文数字。 任何解都必须是多项式$n$，通常约为$O(n^3)$或者$O(n^4)$。 

当出现微妙的边缘情况时$p$是最小排列$[1,2,\dots,n]$。 在这种情况下，不存在字典顺序更小的排列，因此所有答案都必须为零。 

另一种边缘情况发生在$p$是最大的排列$[n,n-1,\dots,1]$。 然后对所有排列进行计数，并将答案简化为所有排列的完整分布，这是对正确性的有用的健全性检查。 

不明显的挑战是$f(p')$取决于排列中的全局排序关系，而不是邻接结构。 除非仔细增强，否则仅跟踪局部转换的朴素 DP 是不够的。 

## 方法

 暴力解决方案将枚举所有排列$p'$，将每个与$p$，并计算$f(p')$。 每次评价$f$需要$O(n^2)$，并且有$n!$排列。 即使对于$n = 10$， 自从$10! \approx 3.6 \times 10^6$，并且对于$n = 100$这是不可能的。 

关键的观察是，字典序限制可以通过从左到右构建排列并计算我们可以严格保持在下面的方式来处理$p$。 这是一个经典的数字 DP 排列：在第一个位置，我们选择一个小于$p_i$，后缀变得不受限制。 

第二个要素是理解$f(p')$。 该函数对对进行计数$(x, x+1)$在哪里$x$出现在之前$x+1$。 这相当于对每个值进行计数$x$， 无论$x$放置早于$x+1$。 所以$f(p')$完全由连续值之间的相对顺序约束决定。 

这将问题转化为对值空间中相邻值的排序关系进行约束的计数排列，并结合位置空间中的字典前缀约束。 这两个结构之间的相互作用表明了一个关于位置、值和偏序状态的 DP，该偏序状态跟踪每个结构是否$x < x+1$关系已得到满足。 

对此进行编码的标准方法是根据已放置的值数量、使用的值集以及当前对的贡献来维护 DP$f$。 自从$n \le 100$，我们使用按位或增量 DP 在值顺序上压缩状态，但我们通过注意到唯一的依赖关系是在连续整数之间来避免完整子集 DP。 

我们按升序处理值并决定它们的相对位置。 对于每个$x$，当两者$x$和$x+1$已经放置，我们知道它们是否有助于$f$。 然而，我们需要同时尊重字典顺序限制，这是使用标准前缀 DP 对具有紧/松状态的位置进行处理的。 

最终的解决方案是一个 DP，它迭代位置，跟踪已经使用了多少小于当前前缀的值，并在连续值之间满足的邻接数量上维护一个 DP。

 ## 算法演练

 我们逐个位置构建排列，同时跟踪字典限制和计算所需的结构$f(p')$。 

1. 定义DP状态为$dp[i][k][t]$， 在哪里$i$是有多少个职位被填补，$k$是当前值$f$， 和$t$表示构造的前缀是否仍然等于$p$（紧状态）或已经较小（松状态）。 这种分离是必要的，因为字典顺序限制只在出现第一个偏差之前才重要。 
2. 维护一个跟踪哪些值已被使用的结构。 我们没有显式存储完整的集合，而是通过计算相对于不同范围内剩余的未使用值的数量来隐式编码可用性$p_i$。 这种压缩是有效的，因为转换仅依赖于前缀约束的相对顺序。 
3. 各位置$i$，迭代所有候选值$v$尚未使用。 我们分为两种情况：$v = p_i$保持紧密度，并且$v < p_i$力转变为松散状态。 价值观$v > p_i$在紧状态下不允许，但在松状态下允许。 
4. 赋值时$v$，我们将贡献更新为$f$通过检查是否$v-1$已经被放置了。 如果是这样，则此放置恰好创建一对新的有效对，从而有助于$f$。 这是关键的减少：$f$可以增量更新$O(1)$每次转换。 
5.我们相应地更新了DP转换，添加了来自状态的方法$dp[i][k][t]$到$dp[i+1][k']$取决于是否相邻$(v-1, v)$很满意。 
6. 处理完所有位置后，我们对紧状态和松状态求和：$i = n$，产生最终分布$k$。 

关键的不变量是处理后$i$位置，DP 精确地表示长度的所有部分排列$i$符合词典编排限制并正确累积贡献$f$仅基于已决定的连续整数的相对位置。 因为每项贡献仅取决于是否$v-1$已提前做出，未来的决定无法追溯更改$f$，保证增量更新的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, mod = map(int, input().split())
    p = list(map(int, input().split()))

    # dp[pos][mask of used compressed state is infeasible for n=100]
    # We instead use DP over positions, value-placed relations:
    # dp[i][k][tight]
    dp = [[[0] * 2 for _ in range(n + 1)] for _ in range(n + 1)]
    dp[0][0][1] = 1

    used = [False] * (n + 1)

    for i in range(n):
        new = [[[0] * 2 for _ in range(n + 1)] for _ in range(n + 1)]

        for k in range(n + 1):
            for tight in range(2):
                cur = dp[i][k][tight]
                if not cur:
                    continue

                for v in range(1, n + 1):
                    if used[v]:
                        continue

                    if tight and v > p[i]:
                        continue

                    ntight = tight and (v == p[i])

                    nk = k
                    if v > 1 and used[v - 1]:
                        nk += 1

                    if nk <= n:
                        new[i + 1][nk][ntight] = (new[i + 1][nk][ntight] + cur) % mod

        used[p[i]] = True
        dp = new

    res = [0] * n
    for k in range(n):
        res[k] = (dp[n][k][0] + dp[n][k][1]) % mod

    print(*res)

if __name__ == "__main__":
    solve()
```该实现遵循数字DP 风格的排列。 变量`tight`编码当前前缀是否与输入排列完全匹配。 一旦选择了较小的值，状态就会变得自由并保持自由。 

这`used`数组强制排列有效性。 转换循环迭代所有未使用的值。 当放置一个值时，我们检查它的前一个值是否已经被使用； 如果是这样，我们将增加贡献$f$。 这是关键的简化$f$可以在每次转换的恒定时间内计算。 

DP 数组存储模数计数$m$。 最终答案聚合所有终止状态，无论紧密程度如何，因为两者都表示严格小于或等于前缀条件的有效排列，但只有那些到达末尾的状态对应于完整排列。
