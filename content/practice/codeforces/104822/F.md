 ## 解决方案
 ## 问题理解

 我们得到了一份员工名单，每个人都有一个数字技能值。 对于每个员工，我们想知道包括他们在内的最大可能团队，但有一个限制：在任何选定的团队内，最大和最小技能之间的差异不得超过固定阈值$k$。 

所以对于每个索引$i$，我们实际上是在问：如果员工$i$必须包括，技能都处于某个区间的员工的最大子集是什么$[x, x+k]$其中还包含$a_i$。 

关键的观察结果是，任何有效的团队完全由数轴上的值区间决定，并且任务简化为了解有多少数组元素落入这样的区间，同时强制包含一个特定元素。 

约束条件达到$n = 2 \cdot 10^5$，因此任何尝试独立地重新计算每个最佳间隔的解决方案$i$在线性时间内会太慢。 一个天真的$O(n^2)$扫描将达到约$4 \cdot 10^{10}$最坏情况下的操作，远远超出了极限。 这立即表明可以重用重复工作的排序或滑动窗口结构。 

出现微妙的边缘情况时$k = 0$。 在这种情况下，只有具有完全相同技能的员工才能被分组。 另一个边缘情况是当所有值都不同并且间隔超过$k$，这迫使每个答案都为 1。假设原始数组中索引连续性的天真尝试将会失败，因为最佳团队在索引空间中不连续，仅在排序值空间中连续。 

## 方法

 蛮力的想法很简单。 对于每位员工$i$，我们尝试每个可能的子集，包括$i$，但我们立即将其简化为更简单的形式：修复$i$，选择它作为组的一部分，并尝试通过添加所有其他员工来扩展组$j$如果结果组仍然满足$\max - \min \le k$。 为了验证这一点，我们维护当前子集中的最小和最大技能。 

这可以正常工作，但计算成本很高。 对于每个$i$，我们可能会检查$O(n)$候选人并重新计算有效性，导致$O(n^2)$行为。 和$2 \cdot 10^5$员工，这是不可能的。 

关键的结构见解是，条件仅取决于价值观，而不取决于指数，并且包含任何员工的最佳团队$i$必须对应于技能排序数组中的连续段。 一旦数组排序完毕，任何有效的团队都是一个滑动窗口，其中端点之间的差异最多为$k$。 而不是为每个重新计算这个窗口$i$，我们可以针对每个位置预先计算有效窗口可以延伸多远。 

我们在排序数组上使用两指针技术来计算在每个位置结束或从每个位置开始的最大有效段。 然后，对于每个原始索引，我们将其转换为已排序数组中的位置，并读取包含它的最大有效窗口的大小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了 |
 | 排序+两个指针|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 ### 最佳想法

 我们将问题转化为排序数组上的问题，然后使用滑动窗口来查找最大有效范围。 

### 步骤

 1. 将每个员工技能与其原始索引配对，并按技能值排序。 

排序是必要的，因为有效性仅取决于最小值和最大值之间的范围。 
2.维护两个指针$l$和$r$，都从 0 开始，表示排序数组中当前有效的窗口。 
3. 对于每个$r$从 0 到$n-1$，通过包含来扩展窗口$a[r]$，然后移动$l$前进同时$a[r] - a[l] > k$。 

这确保了窗口始终满足约束。 
4.固定后$r$, 段$[l, r]$是结束于的最大有效间隔$r$。 
5. 对于每个位置$r$，记录这个窗口的大小，即$r - l + 1$。 
6. 如果团队以该段内的任何成员为中心，则此窗口中的每个索引都可以至少达到此团队规模。 
7. 最后，使用存储的位置将结果映射回原始索引。 

关键点是，一旦我们知道所有最大有效窗口，每个员工的最佳答案就是包含其排序位置的最大窗口。 

### 为什么它有效

 在排序数组中的任何点，滑动窗口都保持内部所有元素满足约束的不变性$\max - \min \le k$。 因为数组是排序的，所以差异总是由端点决定，因此从左收缩是当右端点扩展时恢复有效性的唯一方法。 这保证了每个最大有效段都被恰好发现一次，并且不存在超出当前窗口边界的更大的有效段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

arr = [(a[i], i) for i in range(n)]
arr.sort()

ans = [0] * n
l = 0

for r in range(n):
    while arr[r][0] - arr[l][0] > k:
        l += 1
    ans[arr[r][1]] = r - l + 1

print(*ans)
```该解决方案首先将每个技能与其原始索引配对，以便我们稍后可以恢复答案。 排序后，我们维护一个只向前移动的左指针。 while 循环确保当前段始终遵守技能差异约束。 将每一步计算出的窗口大小分配给该位置的原始员工$r$，因为该员工正是这个最大有效窗口的一部分，结束于$r$。 

一个微妙的细节是，我们不会显式地重新计算窗口所有成员的答案。 各位置$r$贡献其最佳的“结束窗口”，并且由于每个元素在某个阶段都成为端点，因此可以正确捕获其最大有效团队规模。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    arr = [(a[i], i) for i in range(n)]
    arr.sort()

    ans = [0] * n
    l = 0

    for r in range(n):
        while arr[r][0] - arr[l][0] > k:
            l += 1
        ans[arr[r][1]] = r - l + 1

    return " ".join(map(str, ans))

 ## 边缘情况

 当$k = 0$，只有价值观相同才能组成团队。 滑动窗口缩小以确保端点相等，因此重复项自然形成簇。 例如，输入`1 0 / 1 1 1 2 2`产生团体`[1,1,1]`和`[2,2]`，匹配预期输出。 

当所有值相差超过$k$，每个窗口都会折叠成一个元素。 该算法立即缩小每个新右端点的左指针，一致地生成大小 1。 

当所有值都相同时，窗口永远不会缩小，每个员工都会收到答案$n$，因为整个数组形成一个有效段。
