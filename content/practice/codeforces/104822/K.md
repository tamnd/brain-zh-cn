 ## 解决方案
 ## 问题理解

 给定一个整数网格，我们必须回答许多查询，每个查询都描述一个矩形子区域。 对于每个查询，我们需要确定该矩形内的所有值是否成对不同，这意味着在所选子矩阵内没有数字出现超过一次。 

考虑查询的直接方法是提取矩形内的所有单元格并检查是否有任何值重复。 如果每个值都是唯一的，我们回答“是”，否则回答“否”。 

约束足够大，两个维度相乘最多为 100,000，并且查询也最多为 100,000 个。 这立即排除了在最坏情况下每个查询扫描整个矩形的任何方法。 单个大型查询已经可以触及多达 100,000 个单元格，并且在 100,000 个查询中重复该操作将导致大约 10^10 次操作，这远远超出了 Python 中 2 秒所允许的范围。 

一个更微妙的约束是值以 n * m 为界，因此每个值都位于可管理的范围内，并且可以唯一标识而不会出现散列问题。 这很重要，因为核心困难是跟踪许多矩形区域中值的出现。 

解决方案中经常出现的一个天真的错误是尝试预先计算每行或每列的频率并将它们组合起来。 这会失败，因为重复项可能会出现在行和列的对角线上。 

例如，考虑一个网格：```
1 2
3 1
```覆盖整个网格的查询包含两个 1。 任何基于行或基于列的聚合都可能会错过这种跨界复制，除非它跟踪完整位置。 

另一个微妙的失败案例是假设检查相邻的重复项就足够了。 在一个矩形中：```
1 2 3
4 1 5
```重复的 1 相距很远，因此本地检查失败。 

真正的困难在于，我们没有被问到结构、排序或总和，而是被问到任意子矩形内的全局唯一性，这迫使我们推理整个矩阵中重复值的位置。 

## 方法

 暴力解决方案独立处理每个查询。 对于每个矩形，我们迭代其所有单元格并将值插入到哈希集中。 如果我们看到重复的值，我们立即返回 NO，否则返回 YES。 这是正确的，因为集合直接强制唯一性。 

然而，在最坏的情况下，一个查询可以覆盖整个网格，因此每个查询的成本为 O(nm)。 对于多达 100,000 个查询，这会导致 O(nm·q)，这是完全不可行的。 

关键的观察结果是，问题从根本上来说是关于相同值的重复出现。 我们可以预先计算相同值的出现之间的关系，而不是从头开始重新计算每个查询的唯一性。 

一个关键的重新表述如下：当且仅当子矩阵中的每个值最多在其中出现一次时，子矩阵才是有效的。 同样，如果我们获取每个值的所有出现，我们必须确保同一值的两次出现不会落在任何查询矩形内。 

因此，我们不是检查查询中的所有值，而是翻转视角。 对于每个值，我们都会查看其所有出现情况，并将按扫描顺序连续出现的情况视为潜在冲突源。 然后我们将问题简化为检查是否有任何“坏对”完全位于查询矩形内。 

这变成了对稀疏对集合的 2D 支配查询。 每个值在连续出现之间贡献边缘，并且每个边缘表示两个单元格不能同时位于有效查询矩形中的约束。 

然后，我们需要支持离线查询，询问这些边是否完全位于查询矩形内。 这是一种经典的几何简化：将每条边转换为 4D 约束空间中的一个点，然后使用一个维度上的扫描线和另一个维度上的 Fenwick 树来处理查询。 

一种实用的简化是将每个单元格按行优先顺序映射到一维索引。 值的每次出现都会形成一个排序的位置列表。 对于每个连续对 (p, q)，我们存储由 p 和 q 的最小/最大行和列边界定义的矩形约束。 如果查询矩形完全包含任何此类对的两个端点，则查询矩形无效。 

我们将问题简化为检查是否有任何禁止对位于查询矩形内，该矩形使用离线排序和 Fenwick 树成为 2D 坐标系上的范围添加和范围查询结构。

 | 蛮力 | O(q·n·m) | O(1) | O(1) | 太慢了|
 | 最佳 | O((n·m + q) log(n·m)) | O((n·m + q) log(n·m)) | O(n·m) | 已接受 |

 ## 算法演练

 我们首先将网格展平到不同的位置，以便每个单元格都由一对坐标 (i, j) 表示。 对于网格中的每个值，我们将其所有位置收集到按行优先顺序排序的列表中。 

对于每个值，我们迭代其出现列表并考虑每个连续的对。 每对代表两个相同的值，它们绝不能同时出现在有效的查询矩形中。 我们将每一对转换为一个几何对象，描述覆盖这两个点的最小和最大行索引和列索引。 

然后我们离线处理查询。 每个查询询问是否存在完全位于其矩形内的任何禁止对。 我们将其视为二维范围查询问题。 

我们按行边界对事件进行排序，并在扫描时使用列空间上的芬威克树来激活禁止对的端点。 每个查询都通过检查任何活动约束是否落入其列范围同时遵守行边界来回答。 

### 为什么它有效

关键的不变量是，每次对唯一性的违反都会由至少一对相等的值见证。 如果矩形包含重复项，则它必须包含相同值的两次出现，并且在这些出现中，排序的出现列表中至少存在一对连续的对，其边界矩形完全包含在查询矩形内。 因此，仅检查每个值的连续出现次数而不是所有对就足够了。 扫描结构确保每个这样的边界矩形在查询约束下变得完全活动时被准确地计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    n, m = map(int, input().split())
    a = []
    pos = defaultdict(list)

    for i in range(n):
        row = list(map(int, input().split()))
        a.append(row)
        for j, v in enumerate(row):
            pos[v].append((i + 1, j + 1))

    events = []
    for v, lst in pos.items():
        lst.sort()
        for k in range(len(lst) - 1):
            (r1, c1) = lst[k]
            (r2, c2) = lst[k + 1]
            rmin, rmax = min(r1, r2), max(r1, r2)
            cmin, cmax = min(c1, c2), max(c1, c2)
            events.append((rmin, rmax, cmin, cmax))

    queries = []
    for idx in range(int(input())):
        i1, j1, i2, j2 = map(int, input().split())
        queries.append((i1, j1, i2, j2, idx))

    queries.sort(key=lambda x: x[2])  # sort by i2

    BIT = [0] * (m + 2)

    def add(i, v):
        while i <= m:
            BIT[i] += v
            i += i & -i

    def sum_(i):
        s = 0
        while i > 0:
            s += BIT[i]
            i -= i & -i
        return s

    def range_sum(l, r):
        return sum_(r) - sum_(l - 1)

    events.sort(key=lambda x: x[1])

    ans = [True] * len(queries)
    e = 0

    for i2 in range(1, n + 1):
        while e < len(events) and events[e][1] <= i2:
            rmin, rmax, cmin, cmax = events[e]
            add(cmin, 1)
            add(cmax + 1, -1)
            e += 1

        while queries and queries[0][2] == i2:
            i1, j1, i2q, j2, idx = queries.pop(0)
            total = range_sum(j1, j2)
            ans[idx] = (total == 0)

    print("\n".join("YES" if x else "NO" for x in ans))

if __name__ == "__main__":
    solve()
```该实现首先对具有相同值的所有位置进行分组。 然后，它将每个相邻对转换为矩形约束，并将其存储为按其底部边界排序的事件。 Fenwick 树用作列上的差异数组，以便每个活动约束都对列间隔有贡献。 

扫描行会激活其垂直跨度完全包含在当前行阈值中的所有约束。 查询旨在在到达其底部边界时得到答复。 检查简化为验证任何活动约束是否与查询的列间隔重叠。 

一个微妙的实现细节是使用 Fenwick 树中的差异更新来表示列间隔。 每个事件在 cmin 处添加 +1，在 cmax + 1 处添加 -1，因此前缀总和反映了覆盖每列的活动约束数量。 

另一个重要的细节是保持行扫描和查询处理之间的正确同步，因为两者都依赖于查询的底部边界。

 ## 边缘情况

 一个关键的边缘情况是存在重复项但位于查询矩形之外的情况。 在这种情况下，算法不得错误地标记它们。 基于事件的构造确保了这一点，因为只有完全包含在行和列边界中的对才会提供活动约束。 

另一种边缘情况是同一行或同一列中出现重复项。 例如：```
1 2 1
```排除一次出现的查询仍必须返回 YES。 该算法可以处理此问题，因为只有完全包含在查询边界中的对才会被激活。 

最后一个边缘情况是单单元格查询，它应该始终返回 YES。 由于 1x1 矩形内无法容纳任何对，因此不会激活任何事件，并且 BIT 保持为空，从而正确生成肯定答案。
