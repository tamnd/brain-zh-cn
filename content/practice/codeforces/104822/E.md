 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，并且我们可以在任何我们喜欢的地方删除字符。 删除后，我们查看剩余的序列，我们希望它避免一种非常特殊的局部无序：三个连续位置（不一定在原始字符串中相邻，但在结果字符串中连续）可能形成`010`或者`101`。 

换句话说，一旦我们完成删除字符，剩余字符串的每个长度为 3 的窗口必须是常量（`000`,`111`）或至多有一个过渡方向，但它永远不能在三个位置上翻转两次。 

任务是计算使最终字符串满足此条件所需的最小删除次数。 同样，我们希望保留不包含这些禁止模式的最长可能的子序列，因为删除只是`n minus kept length`。 

这些约束允许所有测试用例最多使用 300,000 个字符。 这立即排除了对子串或删除的任何三次或二次方法。 每个测试用例超出线性或接近线性的任何东西都会太慢。 在嵌套循环中重新计算每个位置的任何内容的解决方案将无法在完整输入中生存。 

一个微妙的点是，条件是关于删除后的子序列，而不是原始字符串的子字符串。 这使得简单的模式消除产生误导，因为删除一个字符可以同时破坏许多禁止的三元组。 

一种幼稚的方法可能会尝试贪婪地扫描并删除任何模式`010`或者`101`出现。 这会失败，因为局部贪婪删除会破坏全局最优结构。 

例如，考虑`01010`。 贪婪删除可能会删除第一个的中间字符`010`，生产`0110`，然后继续并删除更多内容，以比必要的更短的结果结束。 相反，最优策略保留结构化子序列，例如`000`或者`111`或单开关形式，具体取决于计数。 

关键的困难在于，删除角色会改变全局的邻接关系，因此局部修复并不稳定。 

## 方法

 暴力解决方案将尝试每个字符子集，检查结果字符串是否有效，并跟踪最大大小。 即使我们只考虑子序列，也有`2^n`可能性，以及每次有效性检查的成本`O(n)`，导致不可能的指数爆炸。 

结构洞察力是令人生畏的`010`和`101`删除所有长度为 3 的交替模式。避免它们的字符串不能“两次切换方向”。 一旦从0到1，以后就不能再回到0，反之亦然。 这意味着每个有效字符串在字符之间最多只能有一次转换。 

因此，每个有效的最终字符串必须是以下三种形式之一：全零、全一、零后跟一或一后跟零。 

一旦看到这一点，问题就变成了四个简单模板下的最长子序列问题。 对于每个模板，我们计算可以保留的最大字符数，然后从中减去`n`。 

我们可以使用前缀和后缀计数在线性时间内计算每种情况。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们想要符合允许的结构形式之一的最长子序列。 我们独立评估每种形式并选择最好的。 

1. 计算字符串中 0 和 1 的前缀计数。 

这使我们能够快速知道任何前缀或后缀中存在多少个每个字符。 
2.考虑最终字符串为all的情况`0`。 

我们能做的最好的事情就是保留原始字符串中的每个零。 这有助于`count(0)`。 
3.考虑最终字符串为all的情况`1`。 

同样，我们可以保留所有的人，做出贡献`count(1)`。 
4.考虑形式`0*1*`，意思是先有一些零，然后是一些，按这个顺序。 

我们选择一个分割点`i`。 左侧保留的所有内容都必须为零，右侧保留的所有内容都必须为 1。 

所以分裂的分数`i`是：`zeros in prefix [0..i] + ones in suffix [i+1..n-1]`。 
5. 扫描所有分割位置并计算最佳可能值`0*1*`。 

这捕获了允许从 0 到 1 的一次转换且没有任何返回的最佳方式。 
6. 重复对称构造`1*0*`。 

对于每个分割，计算：`ones in prefix + zeros in suffix`。 
7. 取四种情况中的最大值。 

答案是`n - best_kept`。 

### 为什么它有效

 任何有效的最终字符串不能包含这两种模式`010`和`101`，这意味着它不能两次交替方向。 这一限制强制字符序列在压缩为运行时最多具有一次值更改。 因此，每个有效子序列必须属于上面列举的四个结构族之一。 由于每个候选族都在该约束下明确评估其最大可能子序列，因此其中的最大值是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input().strip())
        s = input().strip()

        pref0 = [0] * (n + 1)
        pref1 = [0] * (n + 1)

        for i, ch in enumerate(s):
            pref0[i + 1] = pref0[i]
            pref1[i + 1] = pref1[i]
            if ch == '0':
                pref0[i + 1] += 1
            else:
                pref1[i + 1] += 1

        total0 = pref0[n]
        total1 = pref1[n]

        best = max(total0, total1)

        for i in range(n + 1):
            best = max(best, pref0[i] + (total1 - pref1[i]))
            best = max(best, pref1[i] + (total0 - pref0[i]))

        print(n - best)

if __name__ == "__main__":
    solve()
```该实现为 0 和 1 构建前缀和，以便任何前缀或后缀查询都变为 O(1)。 分割位置上的循环以每个位置的恒定时间评估两个过渡方向。 最后的减法将最大保留子序列长度转换为最小删除。 

一个常见的错误是忘记分割是包含-排除的，因此前缀使用`i`和后缀用途`i`小心翼翼地前进。 另一个是重复计算，可以通过使用互补的前缀后缀对来避免。 

## 工作示例

 ### 示例 1

 考虑`s = 00110`。 

我们计算前缀计数：

 | 我| 前缀 0 | 前缀 1 |
 | ---| ---| ---|
 | 0 | 0 | 0 |
 | 1 | 1 | 0 |
 | 2 | 2 | 0 |
 | 3 | 2 | 1 |
 | 4 | 2 | 2 |
 | 5 | 3 | 2 |

 零总数 = 3，一总数 = 2。 

我们评估分割贡献：

 | 分割我| 0_1_ 值 | 1_0_ 值 |
 | ---| ---| ---|
 | 0 | 0 + 2 = 2 | 0 + 3 = 3 |
 | 2 | 2 + 2 = 4 | 0 + 3 = 3 |
 | 3 | 2 + 1 = 3 | 1 + 3 = 4 |
 | 5 | 3 + 0 = 3 | 2 + 0 = 2 |

 最佳保持长度是 4，所以答案是`5 - 4 = 1`。 

这符合删除单个字符可以强制执行干净单调结构的直觉。 

### 示例 2

 采取`s = 01010`。 

前缀计数：

 | 我| 0 | 1 |
 | ---| ---| ---|
 | 0 | 0 | 0 |
 | 1 | 0 | 1 |
 | 2 | 1 | 1 |
 | 3 | 1 | 2 |
 | 4 | 2 | 2 |
 | 5 | 2 | 3 |

 总零 = 2，一 = 3。 

最佳分割评估显示最佳保留子序列为 3，给出答案 2。 

该痕迹表明，如果没有删除，交替结构就无法生存，因为任何保留两个方向的尝试都会强制禁止三元组。

 ## 边缘情况

 对于像这样的单个字符`0`，该算法计算所有转换形式都分解为平凡值的前缀值。 最佳保留长度变为 1，产生零删除，这与预期输出匹配。 

对于已经统一的字符串，例如`00000`，所有配置中最好的就是保持全零。 分割逻辑永远不会超过总零计数，因此结果是零删除。 

对于完全交替的字符串，例如`010101`，每次分裂仍然会迫使要么破坏交替，要么丢弃一半的结构。 前缀-后缀评估正确地捕获了没有长交替子序列是有效的，并且最佳保持长度稳定在一个小常数。 

对于像这样的块结构字符串`001111`，最佳分割与块之间的自然边界对齐。 这`0*1*`case 保留了所有内容，算法选择全长，产生零删除。
