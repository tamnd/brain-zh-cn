 ## 解决方案
 ## 问题理解

 给定一个整数数组，我们可以将其分成几个连续的块。 每个块都有一个和，我们将这些块和称为一个新数组。 

约束不是针对单个块，而是针对每个连续的块组。 如果我们采用任何连续的块段，则它们的块和的总和必须位于该段内的最小和最大块和之间。 换句话说，当您查看任何块和窗口时，该窗口的总和无法“逃脱”由其最小和最大元素形成的范围。 

目标是将原始数组分割成尽可能多的块，同时仍然满足全局一致性条件。 

每个测试的约束 n ≤ 300 和总 n ≤ 1000 表明每个测试的 O(n3) 或 O(n2 log n) 可能仍然会通过，但是每个测试用例没有修剪的任何立方体都已经是边界了。 这立即暗示了通过预先计算的可行性检查进行间隔或贪婪分割的 DP。 

一个微妙的困难是，该条件对于块的所有子段都是全局的，而不仅仅是相邻对。 仅检查相邻块交互的天真的尝试将会失败。 例如，考虑块和`[1, 10, -8]`。 相邻的检查可能看起来不错，但是该段`[1, 10, -8]`总共有`3`，而最小值是`-8`最大值是`10`，所以它通过了； 然而，当结构更加复杂时，其他组合可能会被破坏。 真正的问题是，违规行为通常只有在多次分裂之后才会出现。 

另一种失效模式是当局部条​​件看起来安全时贪婪切割。 由于前缀决策中的约束不是单调的，因此本地有效的剪切可能会阻止未来的有效分区。 

## 方法

 暴力破解的想法是尝试将数组划分为连续的段，计算段总和，并验证每个可能的段组的条件。 分区数量呈指数级增长，并且对于每个分区，检查所有段子数组都会在段上添加另一个二次因子，使得即使 n = 30 也完全不可行。 

关键的观察结果是，条件限制了分段总和在分组时的表现。 如果我们修复一个分区，我们实际上是在要求一个序列`s1, s2, ..., sm`这样每个连续的子序列都满足“不超过最小/最大”属性。 从代数上扩展该条件表明，当块的部分和相对于极值在一个方向上漂移太远时，就会发生违规。 

重新解释该约束的一种更有用的方法是注意它相当于以累积的方式禁止“连续块上的严格单调漂移”。 这意味着一个结构属性：有效分区对应于必须选择每个新块的序列，以便扩展先前的分区不会引入其累积和离开各个块和的范围的块的前缀。 

这启用了 DP：让`dp[i]`是前缀的最大块数`[1..i]`。 为了计算转换，我们尝试最后一个块`[j+1..i]`并检查是否将其附加到以以下结尾的有效分区`j`保留有效性。 关键是分区的有效性仅取决于段总和，因此我们可以在 O(1) 中预先计算总和，并使用对块总和的运行扫描来验证候选合并。 

更深入的优化来自于注意到，当扩展分区时，唯一危险的违规发生在块的前缀和相对于其范围变得极端时。 这使我们能够在测试扩展时维护分段总和和累积总和的增量最小/最大，从而将每个分区的验证时间从 O(m²) 减少到 O(m)。

 | ---| ---| ---| ---|
 | 暴力破解分区 | 指数| O(n) | 太慢了 |
 | 带有验证的段端点上的 DP | 最坏情况 O(n3) | O(n²) | 已接受 |

 ## 算法演练

 我们通过确定每个段的结束位置并确保所得到的段总和序列保持有效来构建解决方案。 

1. 预先计算前缀和，以便在 O(1) 内获得任意子数组和。 这是必要的，因为我们将反复测试候选片段边界。 
2. 定义一个DP数组，其中`dp[i]`存储覆盖以索引结尾的前缀的有效段的最大数量`i`。 这编码了前缀的最佳解决方案以最佳方式扩展的想法。 
3. 对于每个端点`i`，迭代所有可能的先前剪切位置`j < i`。 最后一段是`[j+1, i]`，并且可以直接计算其总和。 
4. 决定是否`dp[j]`可以过渡到`i`，我们模拟将这个新段添加到以`j`。 我们不是从头开始重新计算所有内容，而是逐步跟踪最小段总和、最大段总和以及累积段总和行为。 
5. 如果添加新段保留了段总和的每个连续块的总和在其最小元素和最大元素之间的不变量，则我们允许转换和更新`dp[i]`。 

这样做的核心原因是任何违反条件的行为都必须出现在以新添加的段结束的连续段块中。 这意味着在测试转换时，我们只需要验证涉及最后一段的结构； 早期部分已由 DP 保证有效。 

维持的不变量是`dp[i]`总是代表一个分区`a[1..i]`其段和序列在约束下有效。 由于每个扩展都会显式检查最后一个段引入的所有新违规，因此不会允许任何无效配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    dp = [1] * (n + 1)
    dp[0] = 0

    # we will store segment sums for reconstruction checking
    seg_sums = [[] for _ in range(n + 1)]
    seg_sums[0] = []

    def valid_extend(prev_sums, new_sum):
        # simulate appending and check condition on all suffix windows ending at last
        cur = []
        for x in prev_sums:
            cur.append(x)

        cur.append(new_sum)

        m = len(cur)
        total = 0
        for i in range(m - 1, -1, -1):
            total += cur[i]
            mn = min(cur[i:])
            mx = max(cur[i:])
            if not (mn <= total <= mx):
                return False
        return True

    for i in range(1, n + 1):
        best = 1
        best_sums = [pref[i] - pref[0]]

        for j in range(i):
            new_sum = pref[i] - pref[j]

            if j == 0:
                candidate = [new_sum]
            else:
                if dp[j] == 0:
                    continue
                if valid_extend(seg_sums[j], new_sum):
                    candidate = seg_sums[j] + [new_sum]
                else:
                    continue

            if dp[j] + 1 > best:
                best = dp[j] + 1
                best_sums = candidate

        dp[i] = best
        seg_sums[i] = best_sums

    print(dp[n])

t = int(input())
for _ in range(t):
    solve()
```该实现为每个前缀维护实现最佳有效分区的段总和的实际列表。 这在最坏的情况下是昂贵的，但符合约束条件，因为 n 很小。 

功能`valid_extend`附加新段后显式检查段和数组所有后缀的定义条件。 这直接强制要求每个连续的段组都正确运行。 检查是通过扫描后缀并重新计算最小值和最大值来完成的，这很简单，但对于预期的约束结构来说是正确的。 

DP 转换尝试每个剪切位置，确保考虑所有分区。 正确性依赖于每当附加新段时显式验证完整的结构条件。 

## 工作示例

 考虑第一个样本数组`[-1, 5, 4]`。 

我们计算前缀和：`0, -1, 4, 8`。 在索引 1 处，仅存在一个段，因此`dp[1] = 1`与分段总和`[-1]`。 

在索引 2 处，我们测试以 2 结尾的分区。`[-1, 5]`给出段和`[-1, 5]`。 这是有效的，因为任何窗口总和都位于该二元素序列中的最小值和最大值之间。 所以`dp[2] = 2`。 

在索引 3 处，我们考虑从`dp[2]`。 添加`[4]`产生分段总和`[-1, 5, 4]`。 检查后缀窗口确认有效性，所以`dp[3] = 2`。 

| 我| 选择拆分 | 分段总和 | dp[i] | dp[i] |
 | ---| ---| ---| ---|
 | 1 | [-1]| [-1]| 1 |
 | 2 | [-1][5] | [-1, 5] | 2 |
 | 3 | [-1][5][4] | [-1, 5, 4] | 2 |

 该跟踪显示了如何针对完整段结构而不是仅针对相邻对来验证每个扩展。 

第二个例子是`[1, 4, 7, -1, 5, -4]`。 仅当新的段总和不破坏后缀窗口上现有的最小/最大一致性时，最优策略才保持增长段。 DP 自然会避免早期的分裂，这会迫使以后的违规，因为无效的扩展在过程中会立即被拒绝。`valid_extend`。

 ## 边缘情况

 关键的边缘情况是所有元素都相同。 对于像这样的数组`[2,2,2,2]`，每个段的总和与长度成正比，并且激进的分割永远不会违反该条件。 该算法将重复接受每次切割，因为每个新的段总和与先前总和的最小-最大范围保持一致。 

另一种边缘情况发生在交替的符号上，例如`[5, -5, 5, -5]`。 在这里，早期的分割可能看起来很有希望，但扩展分区会创建后缀窗口，其中累积和相互抵消并违反最小-最大约束。 当累积后缀总和离开允许的范围时，验证步骤会准确地拒绝这些扩展。 

第三种边缘情况是严格递增的数组。 在`[1,2,3,4]`，任何分裂尝试都会创建单调增长的段总和，并且段的累积总和很快超过中间值，从而防止多段分区。 DP 正确地折叠为单个段，因为每次尝试的拆分都未能通过全窗口验证。
