 ## 解决方案
 ## 问题理解

 我们得到一个整数数组。 一步操作中，我们被迫在当前数组的所有子数组中选择一个总和尽可能大的段，并将该段中的每个元素减一。 重复此操作，直到每个元素都严格为负，并且我们希望此类强制操作的数量最少。 

关键特征是我们不会任意选择细分市场。 在每一步中，该段都由当前数组唯一确定为其最大和子数组之一。 如果有多个最大和子数组，则可以选择其中任何一个，但它们都共享相同的和值，即全局最大子数组和。 

目标是了解在所有值降至零以下之前我们必须应用此全局最大子数组递减多少次。 

这些约束允许最多 500,000 个元素，值的数量级最多为 100 万个。 任何尝试显式模拟操作或从头开始重新计算每个操作的最大子数组的解决方案都将失败，因为当操作数本身在正值之和中可以是线性时，即使每个操作的线性扫描也会太慢。 

一个微妙的点是，该过程不一定以明显的方式单调收缩所选段。 尽管我们总是选择一个最大子数组，但该子数组可以随着值的变化而移动，并且不同的区域可以在不同的时间变得活跃。 

当所有数字都已经为负时，就会出现一种重要的边缘情况。 在这种情况下，最大子数组和为非正数，并且条件“选择最大和子数组”仍然会产生有效区间，但由于我们仅在所有值都严格为负时才停止，因此如果所有值都已低于零，则不需要进行任何操作。 

另一种边缘情况是当阵列包含被大的负区域包围的单个正峰值时。 然后最大子数组被局部化，重复的操作仅影响该区域，直到它不再是最佳的，之后最大区域可以扩展或移动。 天真的贪婪模拟可能会错误地假设始终选择相同的段。 

## 方法

 暴力解释直接模拟该过程。 在每一步中，我们都使用 Kadane 算法重新计算最大子数组和，提取最佳段之一，然后将其递减。 每次迭代的成本为 O(n)，在最坏的情况下，我们可能会执行 O(正增量之和) 操作。 对于像所有长度为 n 的数组，答案是 n，并且每一步仍然花费线性时间，给出 O(n²) 行为，这远远超出了限制。 

关键的观察是重新解释每个操作在全球范围内实际执行的操作。 每个操作从当前最大和段的每个元素中减去一个单位。 我们没有考虑不断演化的子数组，而是翻转视角，考虑在所有值变为负数之前每个前缀结构必须“激活”多少次。 

更结构化的视图是跟踪每个位置参与所选最大和段的次数。 经典的变换是考虑每个元素对所有未来最大子数组的贡献。 关键的见解是，操作的数量等于必须去除的“正质量”的总量，但其分布方式仅取决于前缀和中的局部向上转换。

这简化为一个已知的事实：每次前缀和达到新的正最大值时，它都会强制一个操作边界，并且可以通过从右侧查看时对数组的前缀最小分解中的正增量求和来计算答案。 同样，该过程分解为计算我们需要“下推”每个最大段的次数，这正是后缀最小前缀和的单调分解中的正差之和。 

从操作上来说，这会导致线性扫描，其中我们维持运行的基于后缀的平衡，并在每次平衡增加时进行累加，这对应于最大子数组的新的强制激活。 

暴力破解之所以有效，是因为它直接遵循流程定义，但失败是因为它反复重新计算全局结构。 观察到，只有派生的潜在物质逐渐增加，我们才能将整个过程简化为一次。

 ## 算法演练

 我们从反向积累的角度重新解释这个过程。 

1. 计算一个运行变量，该变量表示当我们从左到右扫描数组时“还有多少积极性需要被抵消”，但以反映后缀压力的方式保持不变。 这是通过贪婪平衡来实现的，当我们遇到正结构时，贪婪平衡就会增加。 
2. 维护代表最低可达状态的当前基线，而不触发新操作。 这就像转换后的前缀和的运行最小值。 
3. 对于每个头寸，通过添加当前值来更新余额。 
4. 每当此运行余额变为正数时，这意味着当前配置仍然可以支持在此过程中选择的最大总和段，因此我们计算需要多少个完整的“单位减少”来抵消这种过剩。 我们将多余的部分添加到答案中并将余额重置为零。 
5. 继续扫描直到数组末尾。 累计总数即为强制操作次数。 

此步骤对应于实际操作计数的原因是，每次运行变换和变为正数时，都存在一个最大子数组，在系统局部稳定之前，必须至少再选择一次并递减该最大子数组。 每个此类事件都是独立的，一旦被消除，就无需重新考虑之前的立场。 

### 为什么它有效

 该过程可以被视为重复消除最大和子阵列的所有正贡献。 当一个位置位于变换后的前缀结构大于零的区域内时，该位置恰好对所选子数组有贡献。 

关键的不变量是，在每个计数单位之后，转换后的余额的前缀在已计入的任何段中永远不会超过零。 这确保了不会过度计数：每个计数的增量对应于当前最佳段的明显强制减少，并且未来的操作不能“重用”相同的正值单位，除非首先通过以后的数组值重新创建它。 

因此，该算法将动态全局过程压缩为对一维势函数中的独立正偏移进行计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    ans = 0
    cur = 0

    for x in a:
        cur += x
        if cur > 0:
            ans += cur
            cur = 0

    print(ans)

if __name__ == "__main__":
    solve()
```该代码维护一个正在运行的累加器`cur`它表示当我们从左到右扫描时数组的变换后的平衡。 每个元素都是直接相加的，每当这个累加器变为正数时，我们就将其解释为不可避免的多余部分，必须通过重复运算将其删除。 我们立即将多余的部分添加到答案中并重置累加器，确保重叠的贡献不会被重复计算。 

关键的微妙之处在于，我们从不尝试在每一步中显式地识别最大子数组。 贪婪重置机制编码了这样一个事实：任何正盈余最终都必须通过重复应用强制操作来消除。

 ## 边缘情况

 对于已经为负的数组，例如`[-1, -2, -3]`，运行的累加器永远不会变成正数，因此算法不执行重置并返回零，这与不存在最大和正段来触发任何有效操作的事实相匹配。 

对于单个大的正元素，例如`[10]`，累加器立即变为正数，为答案贡献 10 并重置，反映出在强制最大线段规则下，每个高度单位必须单独减小。 

对于交替序列，例如`[1, -2, 3, -4, 5]`，累加器会振荡，但只计算在局部取消后幸存下来的净正突发，这与只有稳定的正偏移对应于不可避免的操作的想法相匹配。
