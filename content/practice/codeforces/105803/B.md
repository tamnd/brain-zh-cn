 ## 解决方案
 ## 问题理解

 我们有一个`n x n`海滩网格。 除了最后一个孔之外，每个单元格都包含一个箭头，告诉水下一步要去哪里。 水从左上角的单元格进入，必须访问每个单元格一次，最后通过左下角的单元格离开，该单元格标记为`X`。 网格中的一个箭头被更改了，我们需要找到该单元格及其应包含的方向。 

网格坐标基于行和列。 答案是错误箭头的位置和正确的字符`L`,`R`,`U`， 和`D`。 

限制足够大，解必须接近线性。 由于输入上所有网格单元的总和仅为`10^6`，我们可以一次检查每个单元格，但是尝试每条可能的路径或模拟许多候选者之类的事情都太慢了。 预期的解决方案需要`O(n^2)`每个测试用例都可以工作，因为输入本身已经有`n^2`人物。 

主要观察结果是，具有这些固定起始和终止单元的哈密顿路径具有强制形状。 路径必须像蛇一样逐行扫过网格。 首先，它向右移动穿过第一行，然后向下移动一个单元格，然后向左移动穿过第二行，然后再次向下移动，交替方向，直到到达左下角的单元格。 

少数情况下可能会破坏粗心的实现。 

对于一个`2 x 2`网格：```
LD
XL
```答案是：```
1 1 R
```第一行必须从第一个单元格到第二个单元格，因此第一个字符不能是`L`。 

对于一个`3 x 3`网格：```
RRD
LUD
XLL
```答案是：```
2 2 L
```第二行是从右向左遍历的，因此该行的中间单元格必须指向左侧。 假设每行都向右移动的解决方案在这里将失败。 

另一个常见的错误是将最后一个单元格视为普通箭头。 左下角的单元格始终是目标并包含`X`，因此不得根据蛇形图案进行检查。 

## 方法

 一种直接的方法是模拟水的运动`(1,1)`，希望能找到断路的地方。 这适用于检测错误，但它不会立即告诉我们丢失的箭头应该是什么。 错误的箭头可能会将水送入路径的后面部分，从而创建看起来仍然部分有效的遍历。 

暴力修复方法可以尝试将每个单元更改为每个可能的方向，并每次模拟整个路径。 有`n^2`单元格和最多四个可能的方向，以及每个模拟成本`O(n^2)`, 给予`O(n^4)`运营。 和`n`达到`1000`，即周围`10^12`操作，这是不可能的。 

关键的观察是所需的路径不是任意的。 由于路径必须在从左上角开始到左下角结束时恰好覆盖每个单元格一次，因此在移动到下一行之前必须完全遍历每一行。 唯一可能的排列方式就是熟悉的蛇形图案。 

蛮力试图通过探索可能性来发现路径。 这一观察消除了所有可能性：每个单元格都只有一个预期箭头。 我们只需要将给定的网格与该模式进行比较并找到单个不匹配的地方。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n⁴) | O(n²) | 太慢了|
 | 最佳| O(n²) | O(n²) | 已接受 |

 ## 算法演练

 1. 阅读网格并检查除最后一个单元格之外的每个单元格`X`细胞。 

整个任务简化为检查每个箭头是否与唯一可能的有效路径匹配。 
2. 确定当前位置的预期箭头。 

对于除最后一行之外的每一行，基于零的索引中的偶数行向右移动，奇数行向左移动。 每行的最后一个单元格指向下方，以继续蛇形进入下一行。 
3. 将预期的箭头与给定的字符进行比较。 

由于只有一个单元格不正确，因此第一个不匹配就是答案。 
4. 输出行、列以及正确的方向。 

答案中的坐标使用基于一的索引，因此两个索引在打印之前都会增加。 

为什么它有效：

 不变的是，处理任何单元后，每个检查的位置都匹配唯一可以连接所需起点和终点的哈密顿路径。 蛇结构只访问每个单元一次并到达所需的目的地。 由于输入与此有效结构的区别仅在于一个箭头，因此扫描发现的唯一不匹配必定是损坏的单元格，并且预期的字符是所需的纠正。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        grid = [input().strip() for _ in range(n)]

        for r in range(n):
            for c in range(n):
                if r == n - 1 and c == 0:
                    continue

                if r % 2 == 0:
                    if c == n - 1:
                        need = 'D'
                    else:
                        need = 'R'
                else:
                    if c == 0:
                        need = 'D'
                    else:
                        need = 'L'

                if grid[r][c] != need:
                    ans.append(f"{r + 1} {c + 1} {need}")
                    break
            else:
                continue
            break

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```外循环独立处理每个测试用例。 存储网格是因为我们在比较单元格时需要随机访问。 

嵌套循环直接生成预期的蛇方向。 在偶数行上，路径从左向右移动。 该行的最后一个单元格不能向右继续，因为它会离开网格，因此它指向下方。 奇数行对称地工作，从右到左移动并使用第一列向下移动。 

左下角的单元格会被跳过，因为它总是`X`，不是箭头。 这可以避免错误地将目的地视为损坏的单元。 

一旦发现不匹配，搜索立即停止，因为该语句保证恰好有一个不正确的箭头。 仅在打印时应用从一开始的转换，以防止从零开始的循环内出现坐标错误。

## 边缘情况

 对于`2 x 2`例子：```
LD
XL
```该算法检查单元格`(1,1)`。 自行`0`从左向右移动，期望值为`R`， 不是`L`。 它立即输出：```
1 1 R
```对于沿相反方向移动的行：```
RRD
RUL
XLL
```第二行必须从右向左遍历。 细胞`(2,3)`应该指向下方才能进入第三行，但它目前指向左侧。 该算法在验证较早的蛇位置和输出后到达此单元格：```
2 3 D
```对于最终的单元格：```
X
```在左下角，算法完全跳过它。 这可以防止将目的地标记视为损坏的方向。 

对于最大可能的网格，该算法从不构建路径或执行重复模拟。 它只计算每个单元格的一个预期字符，因此运行时间完全随着输入大小的增加而增长。
