 ## 解决方案
 ## 问题理解

 我们给出几个独立的字符串，每个字符串由字符组成`a`,`b`,`c`， 和`?`。 任务是替换每一个`?`与其中一个字母`a`,`b`， 或者`c`使得最终的字符串没有两个相等的相邻字符。 如果在保持这个属性的同时没有办法完成替换，我们就必须报告失败。 

思考这个问题的一个有用的方法是，每个`?`是一个空闲槽，但字符串已经在字母固定的地方施加了约束。 最终字符串必须是 3 个字母字母表上的有效序列，但连续位置不能匹配。 

每个测试用例的约束很小，但所有测试用例的总长度达到 100000。这立即表明每个测试用例策略的线性时间，因为任何比每个字符串 O(n) 更糟糕的操作都有可能在最差聚合中超过约 10^8 操作，这在 Python 中的 1 秒限制中是不安全的。 

一个天真的担忧是，贪婪的本地选择是否会在以后引发矛盾。 另一个微妙的情况是固定字母已经违反规则，例如`"aa?b"`，其中没有替换可以修复初始无效邻接`"aa"`。 该案件必须立即产生`-1`。 

There is also a less obvious failure pattern: a string like`"a??a"`does not always allow a valid fill, because the endpoints force the middle region into a repeating pattern that may collide. 例如`"a??a"`长度为 4 强制中间两个位置以避免两者`a`和彼此，这仍然是可行的，但较长的交替约束可能会阻止某些固定配置中的所有选项。 

## 方法

 暴力方法将对待每个`?`作为三种可能性的分支选择并尝试填充字符串，然后检查有效性。 如果有 k 个问号，则会产生 3^k 种组合。 即使 k 约为 20，这也已经变得不可行，并且这里 k 在整个测试中总共可以达到 10^5。 爆炸性的增长来自于独立地处理选择，而不利用邻接约束纯粹是局部的这一事实。 

关键的观察是每个位置仅与其直接邻居交互。 当从左到右处理字符串时，一旦我们确定了位置 i 的字符，它就只影响 i+1。 这消除了全局依赖性并使贪婪构建变得可行。 

我们不执行分支，而是执行本地规则：当我们遇到`?`，我们选择与其已确定的左邻居不同的任何字母。 后面的位置将类似地解决，并且因为有三个字母，所以只要我们避免违反固定约束，我们总是至少有一个有效的选择。 

我们失败的唯一一次是当固定字母已经创建了无效的邻接时，或者当`?`由于邻居双方都是平等的，并且用尽了所有的选择，因此被迫陷入矛盾。 但对于三个字符，两个禁止的邻居仍然留下一个有效的选择。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 首先，我们检查输入是否已经包含固定字符之间的违规。 我们扫描相邻对，如果我们看到两个不相等的字符`?`，我们已经知道答案是不可能的。 这是必要的，因为`?`无法解决已经存在的矛盾。 
2. 我们将字符串转换为可变数组，以便轻松执行替换。 
3. 我们从左到右扫描。 在每个位置 i，我们决定应该放置什么角色。 
4. 如果角色不是`?`，我们保持原样。 这保留了输入已经强制执行的约束。 
5.如果是`?`，我们尝试分配其中之一`a`,`b`， 或者`c`这样它与前一个字符（如果存在）不同，并且如果下一个字符已经固定，也与下一个字符不同。 我们选择第一个有效的候选人。 
6. 如果无法放置字符，我们立即断定该字符串不能变得漂亮。 
7. 填充后，我们进行最终验证以确保不存在相邻的相等字符，并输出结果。 

为什么这有效来自于约束的结构。 每个位置最多仅禁止两个字母：左侧的字母和右侧的字母（如果已固定）。 由于我们总共有三个字母，因此总是至少有一个可用的选择，除非固定位置已经存在矛盾。 贪婪决策是安全的，因为它永远不会消除直接相邻位置之外的所有未来选项； 每个约束都是局部的和对称的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve(s: str):
    n = len(s)
    s = list(s)

    # early check for fixed contradictions
    for i in range(n - 1):
        if s[i] != '?' and s[i] == s[i + 1]:
            return "-1"

    for i in range(n):
        if s[i] == '?':
            for c in "abc":
                ok = True
                if i > 0 and s[i - 1] == c:
                    ok = False
                if i + 1 < n and s[i + 1] != '?' and s[i + 1] == c:
                    ok = False
                if ok:
                    s[i] = c
                    break
            if s[i] == '?':
                return "-1"

    for i in range(n - 1):
        if s[i] == s[i + 1]:
            return "-1"

    return "".join(s)

def main():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        print(solve(s))

if __name__ == "__main__":
    main()
```该解决方案首先对已固定的字符进行健全性检查，因为任何替换都无法修复已存在的无效邻接。 贪婪填充步骤依赖于以固定顺序尝试字母，但任何顺序都是有效的，因为可行性不取决于最优选择，只取决于存在。 

重要的微妙之处是仅在已知的情况下才检查正确的邻居。 如果我们需要未来的一致性而不允许`?`，我们会过度限制决策。 这种从左到右的处理确保我们永远不会使过去的选择无效。

 ## 边缘情况

 直接失败的情况是固定字符已经违反邻接规则。 用于输入`"aa?b"`，扫描检测到`"aa"`在开始并返回`-1`立即地。 任何替换都不能更改已经固定的字符，因此算法会正确拒绝而不尝试构造。 

另一个微妙的情况是`"a????a"`。 端点迫使内部避免`a`并避免内部重复。 贪心过程从左到右填充，总是至少有一个`{a, b, c}`可以避免前一个字符，并最终产生一个有效的交替模式，例如`"ababca"`或者`"acbac a"`取决于选择。 在分配时只有一个邻居重要的不变性确保端点不会引入超出局部邻接约束的全局矛盾。
