 ## 解决方案

 ## 问题理解

 我们得到了从 1 到 n 的数字排列，我们希望将 1 到 n 中的每个值 m 分类为“好”或“坏”。 如果数组内某处存在一个连续的段，其元素恰好是从 1 到 m 的数字，每个出现一次，则值 m 被认为是好的。 

因此，我们不是选择任意值，而是询问排列是否包含一个连续位置块，其值形成前 m 个整数的完美集合。 

每个测试用例的输出是长度为 n 的二进制字符串。 第 i 个字符表明 i 是否好。 

这些约束很重要，因为测试用例中的 n 可能很大，总共可达 2×10^5。 任何尝试所有子数组并检查它们是否形成有效排列的解决方案都会重复扫描段，从而导致每个测试用例出现二次或更差的行为，这远远超出了 1 秒所允许的范围。 

当思考“只需检查所有子数组并测试它们是否恰好包含 1..m”时，就会出现一个天真的陷阱。 即使对子数组的检查进行了优化，子数组的数量也是 O(n^2)，每次验证的成本至少为 O(n)，除非进行深度优化，这是不可行的。 

另一个微妙的问题是假设如果一个段在某处包含从 1 到 m 的所有值，则它自动有效。 除非段长度恰好为 m 并且不包含该范围之外的额外数字，否则情况并非如此。 

## 方法

 蛮力视角首先固定 m 并扫描所有可能的子数组。 对于每个子数组，我们将跟踪它是否恰好包含集合 {1, 2, ..., m}。 这需要检查完整性以及是否存在超出范围的额外值。 即使使用频率数组，在最坏的情况下我们仍然需要 O(n^2) 个子数组和 O(n) 次更新，导致直接实现中的 O(n^3) 或经过大量预处理的 O(n^2) ，对于 n 高达 2×10^5 的情况仍然失败。 

关键的观察是我们实际上不需要搜索子数组。 相反，我们可以反转视角：固定 m 并查看数字 1 到 m 在排列中的位置。 这些位置唯一地确定了可能包含所有这些位置的任何候选片段。 

如果存在有效段，则它必须包含所有出现的数字 1 到 m。 最小的这样的段是从这些值中的最小位置到这些值中的最大位置。 当该段不包含超出 m 个数字的额外元素时，该段是有效的，而当其长度等于 m 时，就会发生这种情况。 

这将问题转化为随着 m 的增加动态跟踪最小和最大位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^3) 或 O(n^2 log n) | O(n) | 太慢了 |
 | 最佳（位置跟踪）| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们首先计算排列中每个值的位置，以便我们可以快速找到每个数字出现的位置。

1. 构建一个数组 pos，其中 pos[x] 是排列中值 x 的索引。 这允许恒定时间查找每个数字所在的位置。 
2. 用值1的位置初始化两个变量min_pos和max_pos。此时，只考虑数字1，并且包含它的段是普通有效的。 
3. 将 m 从 2 迭代到 n。 对于每个 m，使用 pos[m] 更新 min_pos 和 max_pos。 这些代表值 1 到 m 中的最小和最大索引。 
4. 对每个 m 进行更新后，检查 max_pos - min_pos + 1 是否等于 m。 此条件意味着跨越所有 1..m 出现的区间恰好有 m 个元素，因此其中不能存在额外的数字。 
5.如果条件成立，则将m标记为美丽； 否则，将其标记为不美观。 

### 为什么它有效

 在任何步骤 m，数字 1 到 m 的位置集合是固定的。 任何包含所有这些值的有效段必须至少覆盖从 min_pos 到 max_pos 的范围。 如果该区间恰好有 m 个元素，那么它恰好包含这 m 个位置，而没有其他内容。 由于数组是一个排列，这些位置对应于不同的值，因此该段必须是 1..m 的排列。 如果间隔更大，它将包含集合之外的额外元素，从而无法形成大小为 m 的干净排列。 

这意味着 m 的有效性仅取决于位置的几何形状，而不取决于显式子数组检查。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, v in enumerate(p):
            pos[v] = i

        min_pos = pos[1]
        max_pos = pos[1]

        ans = ["0"] * (n + 1)

        for m in range(1, n + 1):
            idx = pos[m]
            if m == 1:
                min_pos = max_pos = idx
            else:
                if idx < min_pos:
                    min_pos = idx
                if idx > max_pos:
                    max_pos = idx

            if max_pos - min_pos + 1 == m:
                ans[m] = "1"

        out.append("".join(ans[1:]))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案完全依赖于维持值 1 到 m 的位置范围。 pos 数组确保恒定时间访问每个元素的位置。 增量更新避免了为每个 m 从头开始​​重新计算任何内容。 

一个常见的实现错误是通过扫描每个 m 的所有先前值来重新计算最小和最大位置，这会将性能降低到 O(n^2)。 另一个微妙的问题是忘记了 Python 中的索引是从零开始的，因此间隔长度计算必须与该选择保持一致。

 ## 边缘情况

 一种边缘情况是可能的最小排列。 对于单个元素，唯一有效的 m 是 1，并且算法在该单个索引处正确初始化 min_pos 和 max_pos，产生长度为 1 的跨度。 

另一种情况是完全颠倒的排列。 即使元素远未排序，每个前缀 1..m 仍然在索引空间中占据一个连续的段，因此每个 m 通过了跨度测试。 该算法捕获了这一点，因为位置范围仅取决于端点，而不取决于顺序。 

更微妙的情况是值交错时，例如交替小数字和大数字。 该算法正确地失败了中间 m 值，其中 1..m 的位置在索引空间中不连续，即使它们经常彼此靠近。
