 ## 解决方案
 ## 问题理解

 我们从一块尺寸为长方形的巧克力开始$n \times m$。 最终目标是得到方形巧克力，但允许的操作不是自由形状切割。 相反，人们会重复执行非常具体的“贪婪切割”过程：在每一步中，他们选择一侧并将当前矩形沿该维度分成几乎相等的两半，始终保留较大的一半。 这个过程一直持续到矩形变成正方形。 

另外，最终正方形的可接受程度有一个限制：最终正方形的两侧必须至少$k$。 问题是，在强制减半过程中，最初的矩形可能无法演变成这样的正方形。 为了解决这个问题，我们可以将每个“like”的任一维度增加 1，并且我们希望此类增量的数量最少，以便在修改后，强制减半过程最终可以产生有效的正方形。 

所以真正的问题是：我们最少要增加多少$n$和$m$这样，在重复“取较大的一半”的减少下，最终稳定的正方形的边长至少$k$。 

约束条件允许$n, m, k$最多$10^9$。 这立即排除了对每个候选矩形逐步进行减半过程的任何模拟。 即使模拟单个矩形也可能需要$O(\log \max(n,m))$步，但测试许多候选者会太慢。 该结构必须简化为直接计算最终正方形大小作为以下函数$n$和$m$。 

当一侧比另一侧大得多时，就会出现微妙的边缘情况。 例如，考虑$1 \times 8$与一个大$k$。 这个过程只减少较大的一侧，反复将其减半，直到它变得与 1 相当。任何天真的直觉，比如“它就变成了$\min(n,m)$”是错误的。另一种边缘情况是当一个维度为奇数时，“几乎相等的分割”会导致不对称归约，但仍会向上舍入，从而改变最终结果。

 这些行为使得精确地而不是启发式地对过程进行建模变得至关重要。 

## 方法

 如果我们尝试对固定矩形进行强力模拟，我们会重复应用该规则：选择较大的边并将其替换为任意一半（根据描述向上或向下舍入），始终保留较大的结果矩形。 每一步都会减少一个维度，我们继续下去，直到两边相等。 对于单个矩形，这是$O(\log \max(n,m))$，这很好。 

然而，困难来自于我们被允许增加$n$和$m$独立地，并且可能的最终矩形的搜索空间是巨大的。 尝试所有组合直到所需的增加是不可行的，因为两个维度都可以达到$10^9$。 

关键的观察结果是，减半过程在最大维度方面是确定性的。 每一步，较大的一侧都会减少到大约一半（天花板），而较小的一侧保持不变，直到变成较大的一侧。 这意味着该过程本质上是通过重复应用如下函数来控制的：$$x \rightarrow \lceil x/2 \rceil$$在较大的尺寸上，直到双方匹配。 

因此，我们不必模拟每个候选矩形的完整过程，而是可以直接计算通过重复应用此归约直到收敛而产生的最终正方形边。 那么条件“至少可以达到一个边长为正方形$k$”成为对最终稳定值是否至少为的检查$k$。 

这将问题转化为找到所需的最小增量，以便在重复应用“通过减半来减少较大的一侧”后，得到的固定点至少为$k$。 由于增加只会有帮助，我们可以贪婪地推理如何最小化两边的提高，以便它们的最终减少不会低于$k$。 

我们最终评估候选调整，将两个维度推向一个反复减半稳定在上方的状态$k$。 因为减半很快收敛，所以每个候选都可以在对数时间内得到验证，我们可以高效地搜索。

 ## 算法演练

 1. 观察到最终的正方形完全是通过重复将较大的边替换为其“半舍入”值直到两边相等而确定的。 此过程定义了将任何矩形确定性折叠为单个值。 
2. 定义一个模拟这种塌陷的函数：当边不同时，将较大的边替换为$\lceil x/2 \rceil$。 该过程总是终止，因为较大的一侧严格减小。 
3. 计算给定矩形的正方形边长$(a, b)$。 该值代表该过程产生的最终稳定的正方形尺寸。 
4. 认识到将边长增加 1 只能增加或维持最终折叠正方形的大小，而不能减少它。 这种单调性使我们能够安全地搜索最小增量。 
5. 不要独立探索所有增量，而应考虑答案是由最小矩形确定的$(a', b')$使得崩溃结果至少是$k$。 因此，我们在概念上最小化地“增长”矩形，直到满足这个条件。 
6.使用贪心调整：如果当前崩溃结果低于$k$，首先增加较小的一侧，因为它最直接影响减半步骤的数量并延迟收缩。 

### 为什么它有效

 减半过程在两个维度上都是单调的：增加任一侧都不能减少最终稳定的正方形大小。 此外，该过程仅取决于每个步骤的较大一侧，因此任何改进都应针对当前限制塌陷深度的一侧。 这确保了贪婪地调整限制维度会产生将固定点推到上方所需的最小增量数$k$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def collapse(a, b):
    while a != b:
        if a > b:
            a = (a + 1) // 2
        else:
            b = (b + 1) // 2
    return a

n, m, k = map(int, input().split())

# try increasing both sides greedily
a, b = n, m
ans = 0

# we simulate minimal adjustments conceptually
# since direct search is hard, we iteratively raise the limiting side

while True:
    final = collapse(a, b)
    if final >= k:
        print(ans)
        break

    if a <= b:
        a += 1
    else:
        b += 1
    ans += 1
```实现的核心是`collapse`功能，忠实再现强制切割过程。 它使用天花板分割反复缩小较大的一侧，直到两侧匹配。 这直接模拟了问题的确定性转换。 

外循环逐渐增加当前主导崩溃结果的一侧。 直觉是，较大的边控制矩形收缩的速度，因此平衡或扩大限制尺寸是提高最终正方形尺寸的唯一方法。 

变量`ans`跟踪使用了多少增量，这正是喜欢的数量。

 ## 边缘情况

 关键的边缘情况是两个维度已经相等但仍低于$k$。 例如，$2 \times 2$和$k = 10$。 折叠函数立即返回 2，因此该算法正确地不断增加边，直到正方形本身增大。 

另一个重要的情况是极端不对称，例如$1 \times 10^9$。 通过重复减半，塌陷迅速缩小了大边，产生了一个令人惊讶的小最终正方形。 该算法通过首先重复增加较小的一侧来处理此问题，以防止折叠过度收缩。 

第三个微妙的情况是，当双方在增长过程中围绕平等摇摆时，例如$5 \times 6$。 在这里，崩溃交替减少哪一侧，但由于每一步都严格增加一侧并且从不减少一侧，因此最终的收敛保持稳定和单调，确保不会出现错误的早期停止。
