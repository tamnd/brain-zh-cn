 ## 解决方案
 ## 问题理解

 我们得到一个由小写拉丁字母组成的字符串。 每当某个字符出现在至少一个连续的长度块中时，该字符串就会变得“坏”`m`。 我们的目标是转换字符串，使每个相同字符的最大块的长度严格小于`m`。 

我们可以进行两种类型的编辑。 我们可以以成本 1 删除一个字符，这会缩小字符串并连接剩余部分。 我们还可以在任意位置插入任意字符，以节省成本`k`，可用于通过用不同的字母分隔长块来分割它们。 

任务是计算使字符串“好”的最小总成本，这意味着没有相同的字符达到长度`m`。 

约束允许字符串长度高达 200,000，这立即排除了子字符串上的任何二次或三次动态编程。 每次测试都需要线性扫描或接近线性的扫描。 

一个关键的微妙之处是操作可以在本地改变结构。 在块内部删除会直接减少其长度，而插入则可以将一个块分割成多个更小的块，而不会删除字符。 只独立地查看每个块而不考虑拆分与删除的天真的贪婪策略可能会失败。 

当长块稍微超出限制时，就会出现常见的故障情况。 例如，如果`m = 4`如果一个块的长度为 7，则删除 3 个字符的成本为 3，但插入一个字符将其分成长度为 3 和 4 的两个块是无效的，因为第二个块仍然违反了限制。 这表明，只有当每个结果段都遵守约束时，分割才有效。 

真正的决定是针对每个块：要么通过删除来减小其大小，要么保留所有字符并插入分隔符以将其拆分为有效的段。 

## 方法

 如果我们忽略结构并尝试所有方法对整个字符串应用插入和删除，我们很快就会遇到指数爆炸。 即使将我们限制在相同字符的单个连续块中，尝试删除和插入的所有组合也会导致在多种可能性中选择最终配置，并且块之间的全局交互使情况变得更糟。 

关键的观察结果是，字符串自然地分解为相同字符的最大段，并且一个段内的操作不会以有益的方式影响其他段。 不同的字符永远不会合并到更长的有效运行中，因为合并仅在相同的字符变得相邻时发生，而这不能发生在不同的初始块中。 

因此每个最大块都可以独立优化。 

考虑一个长度块`L`。 我们希望以一系列块结束，每个块的大小最多`m-1`。 我们有两种自然策略。 一种是删除字符，直到块本身变得有效，付费`L - (m-1)`如果`L >= m`。 另一种是保留所有字符并插入分隔符，以便将块分割成多个有效块。 如果我们分裂成`t`块，我们需要`t-1`插入次数以及每次插入费用`k`。 约束力`t = ceil(L / (m-1))`。 

这已经给出了强有力的候选人答案。 微妙的一点是，删除和插入的中间混合也存在，但它们会崩溃成一小部分情况：如果我们决定分成`q`片段，我们能做的最好的就是保留尽可能多的原始字符，这意味着在准确保留的同时最大限度地减少删除`q`段。 这导致了段计数的直接公式。 

## 算法演练

 我们通过对连续的相等字符进行分组来处理字符串。 

对于每个长度块`L`，我们独立计算最小成本。 

1. 计算如果我们不删除任何内容，需要多少个段。 这是`q = ceil(L / (m - 1))`。 保留所有角色迫使我们分裂成`q`有效的块。 成本是`(q - 1) * k`。 
2. 计算删除字符的成本，以使块在不分裂的情况下变得有效。 我们最多想要最终的长度`m - 1`，所以成本是`max(0, L - (m - 1))`。 
3. （可选）考虑中间拆分级别。 对于固定数量的段`q`，我们能做的就是最多保留`q * (m - 1)`字符，所以删除是`L - min(L, q * (m - 1))`，并且插入是`(q - 1) * k`。 
4. 在所有可行的方案中取最小值`q`价值观。 在实践中，迭代`q`从 1 到`ceil(L / (m - 1))`就足够了。 
5. 将所有块的这些最小成本相加。 

最终的答案就是总和。 

这种分解起作用的原因是，影响块的每个操作只会更改该块的内部分段，并且块是独立的，因为没有操作可以创建跨越不同字符的新的长期运行。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    s = input().strip()

    ans = 0
    i = 0

    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1

        L = j - i
        lim = m - 1

        # case 1: pure deletions to make single valid block
        best = max(0, L - lim)

        # case 2: splitting into q segments with insertions
        q = 1
        while (q - 1) * lim < L:
            kept = min(L, q * lim)
            cost = (L - kept) + (q - 1) * k
            best = min(best, cost)
            q += 1

        ans += best
        i = j

    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先通过使用两个指针进行扫描来将字符串压缩为串。 对于每次运行，它都会计算其长度并评估可能的成本。 

变量`best`从纯删除策略开始，该策略始终有效，因为它保证运行缩减到阈值以下。 然后我们迭代可能的段数`q`。 对于每个`q`，我们计算在仍然遵守段限制的情况下可以保留多少个字符，并支付分割的插入成本和修剪多余字符的删除成本。 

循环结束`q`是有界的，因为一旦`q * (m - 1)`超过`L`，我们已经涵盖了所有有意义的段计数。

 ## 边缘情况

 一个关键的边缘情况是当块长度恰好是`m-1`。 在这种情况下，分割是干净的，不需要删除，只需要插入。 算法正确评估`q = L / (m-1)`并分配成本`(q-1)*k`，它匹配均匀分割段的最优结构。 

另一种情况是当`k`非常大。 那么插入总是更糟糕，算法自然会选择仅删除选项，因为`best`开始于`L - (m-1)`并且插入成本随着增加`k`。 

最后一个微妙的案例非常小`m`， 尤其`m = 2`，其中禁止每个相邻的重复项。 这里`m-1 = 1`，因此每个块必须完全分开或减少为单个字符。 该算法正确地退化为要么删除每个块中除一个字符之外的所有字符，要么在每一对之间插入分隔符，并且每次运行始终一致地选择最小值。
