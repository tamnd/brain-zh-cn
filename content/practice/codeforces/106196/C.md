 ## 解决方案
 ## 问题理解

 我们有`n`人类和`n`火星人。 人类`i`只被火星人打败`i`，这意味着人类自动赢得所有其他战斗。 初始行不是任意的：位于位置`i`站立着有数字的人`i`，而输入排列告诉我们哪个火星人站在每个位置的对面。 

指挥官可以执行一项操作：将队伍末端的人移到前面。 这是人类安排的右循环移位。 我们需要最少数量的此类转变，之后没有人以相同的数量面对火星人。 如果没有可能的轮班数，我们输出`-1`。 

输入尺寸可以达到`2 * 10^5`，因此尝试每一个可能的转变并检查所有位置的方法将采取`O(n^2)`最坏情况下的操作。 几十万战士，这速度太慢了。 我们需要通过处理一次或几次排列来找到答案。 

一个微妙的点是，有效的安排并不要求人类和火星人处于同一秩序。 唯一被禁止的情况是职位平等。 例如：```
5
1 4 2 3 5
```通过零转变，人类`[1,2,3,4,5]`。 第一个和第五个位置的人类和火星人的数量相等，所以答案不是`0`。 仅检查排列是否已排序的粗心解决方案将在这里失败。 

另一种边缘情况是每次可能的移位都会产生至少一次碰撞：```
5
1 3 5 2 4
```对于这种排列，每种可能的旋转都会让一些人面对相同编号的火星人，因此输出是`-1`。 始终选择第一个缺失位置而不跟踪所有禁止移位的解决方案将产生无效答案。 

最小可能的输入也值得考虑：```
1
1
```只有一名战士。 唯一的安排是人类面对同一个火星人，所以任何转变都无济于事，答案是`-1`。 

## 方法

 最简单的方法是模拟所有可能的操作次数。 对于每个班次从`0`到`n - 1`，我们构建或检查生成的人类位置，并检查某个位置是否包含与那里的火星人相同的数字。 这是正确的，因为每个可达的排列恰好是原始人类线路的一个循环移位。 

问题是运行时间。 有`n`可能的班次，检查一个班次需要查看`n`职位、给予`O(n^2)`工作。 为了`n = 200000`，这意味着大约四百亿张支票。 

关键的观察是每个可能的转变都可以用单个值来描述。 假设我们执行`k`运营。 人站在某个位置`i`是原来位置向前移动了`k`，所以他的号码是：```
((i - k - 1) mod n) + 1
```当该值等于时发生碰撞`a[i]`。 重新整理方程表明，转变`k`恰好在以下情况下很糟糕：```
k = (i - a[i]) mod n
```对于每个位置，我们可以标记使该位置无效的一个转变。 处理完所有位置后，答案是从未标记的最小移位。 

这将问题转化为收集模数禁止的残基`n`，只需要一次通过。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 创建一个数组来存储特定的移位值是否不可能。 正好有`n`可能的班次，编号为`0`到`n - 1`。 
2. 对于每个位置`i`，计算值`(i - a[i]) mod n`使用从零开始的索引。 这个价值是独特的转变，将使人类`a[i]`在此位置并造成损失。 
3. 将此计算出的偏移标记为禁止。 这样做的原因是每个位置只能使一次循环旋转无效。 
4. 从最小值到最大值扫描移位。 不禁止的第一班是所需的最少操作次数。 
5. 如果每个班次都被禁止，则输出`-1`因为每一种可能的最终安排都至少包含一场失败的战斗。 

工作原理：每个循环移位恰好对应一个余数模`n`。 只有当人类数量与火星数量对齐时，位置才会变得糟糕。 通过标记所有这些转变，我们代表了完整的不可能答案集。 任何无标记的转变在任何位置都不会发生碰撞，因此每个人都会获胜。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    bad = [False] * n

    for i, x in enumerate(a):
        shift = (i - (x - 1)) % n
        bad[shift] = True

    for ans in range(n):
        if not bad[ans]:
            print(ans)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```数组`bad`商店禁止轮班。 该代码使用从零开始的位置，因此火星数`x`被转换为`x - 1`在将其与位置索引进行比较之前。 

表达式：```
(i - (x - 1)) % n
```是导出公式的直接实现。 它给出了可以移动人类的正确旋转次数`x`就位`i`。 这样的旋转是无效的，因为人类`x`会遇见火星人`x`。 

最后的循环按升序搜索，这会自动给出最小有效操作数。 这`-1`仅当每个可能的旋转都被标记为禁止时才会发生这种情况。

import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    bad = [False] * n

    for i, x in enumerate(a):
        bad[(i - (x - 1)) % n] = True

    for i in range(n):
        if not bad[i]:
            return str(i)

    return "-1"

assert solve("5\n1 4 2 3 5\n") == "2"
assert solve("5\n1 3 5 2 4\n") == "-1"

assert solve("1\n1\n") == "-1"
assert solve("5\n1 2 3 4 5\n") == "1"
assert solve("6\n2 3 4 5 6 1\n") == "0"

 ## 边缘情况

 对于这个案例：```
1
1
```只有一种可能的位置，唯一的人类面对唯一的火星人。 计算出的禁止位移为`0`，这是整个可能的转变集合。 扫描未发现有效值并返回`-1`。 

对于这个案例：```
5
1 3 5 2 4
```每个移位值都被标记，因为每个可能的循环运动都会产生至少一对相等的人类和火星。 该算法不假设存在解决方案，因此在检查所有班次后，它会正确打印`-1`。 

对于恒等排列：```
5
1 2 3 4 5
```零移是无效的，因为每个人都面临着他们匹配的敌人。 然而，旋转一位会使每个人远离自己的数字，所以移动`1`是第一个未标记的值并被返回。 这捕获了仅检查排列是否已排序而不是检查旋转后的冲突的常见错误。
