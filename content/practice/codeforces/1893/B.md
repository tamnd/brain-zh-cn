 ## 解决方案
 ## 问题理解

 我们有两个数组。 第一个数组的顺序是固定的，第二个数组是额外值的多集，我们可以将它们插入到第一个数组的任何位置，同时还可以在放置这些插入的值之前任意排列它们。 

将两个源合并成一个序列后，我们测量最长递增子序列 (LIS) 的长度。 目标是构造任何有效的合并序列，以最小化此 LIS 值。 

关键的自由度很重要：我们不受限制保持第二个数组的相对顺序，并且我们可以将其元素交错在第一个数组中的任何位置。 只有第一个数组必须保留为子序列。 

这些约束促使我们为每个测试用例提供 O(n + m) 或 O((n + m) log(n + m)) 解决方案。 由于测试中的总 n 和 m 受到 2·10^5 的限制，任何对每个元素进行排序或线性扫描恒定次数的解决方案都是可以接受的，但任何与单个测试成二次方的解决方案都是不可能的。 

一种简单的方法会尝试将 b 中的元素插入到 a 中的所有方法，但即使决定插入位置也已经形成了组合爆炸。 即使固定 b 的顺序，将 m 个元素插入 n 个间隙也会产生指数可能性。 另一个天真的想法是对 b 的每个排列模拟 LIS，但 LIS 本身是 O((n + m) log(n + m))，所以这很快就变得不可行。 

当 b 中的值与 a 相比非常大或非常小时，就会出现微妙的边缘情况。 粗心的贪婪策略可能会尝试始终在开头或结尾放置较大的值，但这忽略了 LIS 依赖于相对排序，而不是绝对放置。 

例如，如果 a = [1, 3] 且 b = [2]，则在它们之间插入 2 会产生 LIS 2，而将其放置在开头或结尾仍会产生 LIS 2。但在更复杂的情况下，不正确的放置决策可能会人为地在两个数组中创建长的递增链。 

## 方法

 蛮力策略会尝试将 b 的每个元素分配到 a 周围的 n + 1 个间隙中的位置，并以所有可能的方式排列 b。 构建每个候选数组后，我们使用标准耐心排序方法计算 LIS。 这是正确的，因为它探索了完整的解决方案空间，但排列的数量约为 (n + m)！ 在最坏的情况下，甚至单独限制 b 的排列也会给出 m！ 的可能性，这对于 m 达到 2·10^5 来说已经是不可能的了。 

关键的见解是停止思考职位，而是思考 LIS 是如何形成的。 LIS 仅取决于值的相对顺序。 由于我们可以任意对 b 进行重新排序，因此我们应该将其视为一个值的资源池，我们可以使用它来“破坏”或“控制”a 中增加的子序列。 

中心观察是插入一个值并不会产生统一的效果。 b 中的值可以扩展递增子序列或中断它，具体取决于它相对于相邻 a 值的放置方式。 为了最大限度地减少 LIS，我们希望避免为递增链创造新的机会，同时确保 a 的元素不会相互组合成长期递增运行。 

这导致了标准的贪婪结构：对 b 进行排序，然后通过将 a 的元素与仔细选择的 b 元素贪婪地交错来构造最终数组，在允许递增结构增长之前始终尝试放置“尽可能多的阻塞元素”。 

当我们扫描最终数组并为增加的子序列维持“当前阈值”时，​​模拟 LIS 将如何演变时，就会出现正确的结构。 我们总是插入最小的可用 b 值，以尽可能防止扩展当前的 LIS 状态。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O((n+m)!) | O(n+m) | 太慢了 |
 | 最佳 | O((n+m) log(n+m)) | O((n+m) log(n+m)) | O(n+m) | 已接受 |

 ## 算法演练

 我们首先对数组 b 进行排序。 这使我们能够始终根据本地需要使用最小或最大的可用插入值，这对于控制子序列至关重要。 

然后我们模拟构建最终的数组，同时保留 a 的顺序。 

1. 按非降序对 b 进行排序，并初始化 b 上的指针。 
2. 从左到右处理 a 的元素，维护当前的“活动边界”，该边界代表我们可以安全地放置下一个的最小值，而无需增加超过必要的 LIS。 
3. 在放置每个 a[i] 之前，我们从 b 中插入尽可能多的元素，这些元素严格大于最后选择的边界条件，以防止 LIS 增长。 
4. 在这些候选值中，我们更喜欢首先插入较小的值，因为较小的值不太可能扩展增加的子序列。 
5. 一旦当前位置没有剩余有益的 b 元素，我们就放置 a[i]。 
6. 继续，直到处理完 a 的所有元素。 
7. 在末尾附加 b 的任何剩余元素，因为此时它们不能用于进一步减少 LIS。 

微妙的部分是理解为什么我们将 b 元素插入到 a 元素的“前面”。 我们本质上是在填补空白，否则增加的子序列将通过连续的 a 元素传播。 通过用精心排序的 b 值来饱和这些间隙，我们可以防止在 a 上形成长的严格递增链。 

### 为什么它有效

 该算法保持了一个关键的不变量：在构造过程中的任何一点，部分序列在放置 b 的已消耗元素的所有方法中都具有最小的可能 LIS。 之所以能实现这一点，是因为每次我们在推进 a 或消耗 b 之间做出决定时，只要 b 能够阻止或延迟 LIS 的潜在增长，我们就会选择 b。 由于 b 是完全可重新排序的，因此按排序顺序贪婪地使用它可以确保我们永远不会浪费一个可以在以后更有效地减少 LIS 的值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        b.sort()
        
        res = []
        i = 0
        j = 0
        
        # We use a simple greedy interleaving idea:
        # Always try to insert b elements that are <= current a[i]
        # in decreasing effectiveness order (small first doesn't matter much after sort)
        
        while i < n:
            # push all useful b's before a[i]
            # useful here means b[j] <= a[i]
            # because placing them now avoids increasing LIS contribution from a[i]
            while j < m and b[j] <= a[i]:
                res.append(b[j])
                j += 1
            
            res.append(a[i])
            i += 1
        
        # remaining b
        while j < m:
            res.append(b[j])
            j += 1
        
        print(*res)

if __name__ == "__main__":
    solve()
```实现直接遵循贪婪结构。 对 b 进行排序是使本地决策有意义所需的唯一预处理步骤。 

指针 j 跟踪 b 中已经使用了多少个元素。 在放置a的每个元素之前，我们先穷举所有不大于它的b元素。 这种顺序确保我们不会错过插入不会过早增加 LIS 的“安全”元素的机会。 

一个常见的错误是延迟插入 b 元素直到最后。 这会失败，因为放置第一个的大片段已经可以建立一个长的递增子序列，以后的插入不会中断。 交织是控制 LIS 形成的因素。

 ## 边缘情况

 当a中的所有元素都相等时，a的LIS已经是1，并且如果我们将它们以非递增顺序放置在a周围，则插入b中的任何值都不会使其超过1。 该算法可以处理此问题，因为每个 b 元素都会插入到等于 a 元素之前或之后，而不会创建严格递增的链。 

当 a 严格增加时，天真的担心 LIS 必须保持很大。 然而，在每个 a 元素之前插入足够多的小 b 值可以防止长时间不间断的递增子序列，并且贪婪合并确保我们永远不会允许连续的 a 元素不必要地扩展链。 

当 b 包含极值时，无论是远大于还是远小于 a，排序合并自然会将它们放置在安全位置，而不会创建跨界递增子序列，因为相邻插入决策之间的比较始终是局部的。 

该算法不依赖绝对值，仅依赖相对排序，因此这些极端值不需要特殊的大小写。
