 ## 解决方案
 ## 问题理解

 我们得到了一组彩色立方体。 立方体的颜色是固定的，但我们可以选择如何将它们分布在架子上以及它们在每个架子上出现的顺序。 

对于货架来说，要求是相同颜色之间的最小距离。 如果一个架子至少有色彩`d`，那么该架子上任何两次出现的相同颜色必须至少分开`d`职位。 另一种说法是，在一个架子内，禁止在前一个架子中出现相同的颜色。`d - 1`职位。 

每个架子都有长度`s_i`以及所需的距离`d_i`。 我们必须为每个架子构建一个实际的颜色序列，每个立方体只使用一次。 

所有测试用例的立方体总数最多为`2 · 10^5`。 这立即排除了任何二次方`n`。 解决方案围绕`O(n log n)`完全舒适，同时`O(n^2)`大致会执行`4 · 10^10`最坏情况下的操作。 

问题的微妙之处在于，架子在最终答案中是独立的，但立方体频率是全局的。 在一个货架上看起来有效的贪婪放置可能会以一种使后面的货架不可能的方式消耗颜色。 

考虑一个架子的尺寸`4`和`d = 2`和四个相同颜色的立方体。 架子需要图案`x ? x ?`，但没有足够的其他颜色来分隔所有副本。 仅检查当前位置的贪婪算法可能会为时已晚。 

另一个容易的错误是将条件视为“相邻立方体必须不同”`d > 2`。 例如：```
s = 5
d = 3
shelf = [1, 2, 1, 3, 4]
```两人`1`s 仅相距两个位置，因此色彩为`2`， 不是`3`。 

第三个陷阱是忘记架子是完全分开的。 在一个架子的末尾和另一个架子的开头使用的颜色不会造成任何违规，因为色彩仅在每个架子内部定义。 

## 方法

 一种强力的观点是一次建立一个位置的货架并尝试仍然有剩余副本的所有颜色。 每当我们放置颜色时，我们都会验证货架的色彩约束是否仍然可以满足。 这在概念上是正确的，因为它探索了所有可能的构造。 

问题在于分支因素。 即使在压缩相同的颜色之后，每一步也可能有数千种不同的选择。 搜索空间呈指数增长。 

关键的观察是具有要求的货架`d`只关心前一个`d - 1`职位。 Once a color is used, it becomes unavailable for the next`d - 1`位置，然后再次可用。 

这看起来像是一个调度问题。 每种颜色都有一个剩余频率。 在目前所有可用的颜色中，使用剩余数量最多的颜色是最安全的选择，因为出现频率高的颜色以后最难放置。 

这表明在具有冷却时间限制的重排问题中使用了经典的贪婪算法。 

对于有距离的架子`d`:```
place a color
temporarily block it
after d steps, unblock it
```在所有未阻塞的颜色中，始终取剩余频率最大的一种。 

美妙之处在于我们不需要单独解决货架问题。 我们按顺序处理货架，同时维护剩余立方体的全局池。 在架子内，颜色会暂时从池中移除，以便准确地`d`职位。 当它们再次合法时，它们将被重新插入。 

如果在某个位置没有可用的颜色，则不存在有效的构造。 官方解决方案正是使用了这种贪婪方法，并设置了按剩余频率排序的集合。

 ## 算法演练

 1. 计算每种颜色有多少个立方体。 
2. 将具有正频率的每种颜色存储在一个有序集合中，键为`(remaining_count, color)`。 
3、将货架一一处理。 
4.对于当前的架子，创建一个长度的数组`s_i`。 
5. 充填位置时`j`,首先检查颜色是否放置在位置`j - d_i`应该再次可用。 如果仍有剩余副本，请将其重新插入集合中。 
6. 如果集合为空，则当前位置不能放置合法颜色。 输出`-1`。 
7. 否则，取剩余频率最大的颜色。 
8. 将其放置在当前位置，从其频率中删除一个副本，并保留其阻止下一个副本`d_i - 1`职位。 
9. 架子完全填满后，释放仍在冷却窗口中等待的所有颜色。 这为下一个架子准备了全局结构。 
10、所有货架加工完成后，输出构建好的货架。 

### 为什么它有效

 在每一步中，该集合都包含可以合法放置在当前位置的颜色。 最后使用的任何颜色`d_i - 1`当前货架的位置暂时被排除。 

在所有合法颜色中，选择剩余频率最大的颜色是冷却调度的标准贪婪策略。 具有许多剩余副本的颜色是最受限制的资源。 推迟只会让未来的安置变得更加困难。 如果贪婪无法放置任何颜色，因为可用集为空，则每个剩余​​颜色当前都被阻止，因此不存在有效的延续。 

不变的是，该集合始终包含所有且仅合法的颜色，并且每个位置都遵循距离要求。 因此，每个生产出来的货架至少具有色彩`d_i`。 公认的 Codeforces 解决方案正是遵循这种结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    s = list(map(int, input().split()))
    d = list(map(int, input().split()))

    cnt = [0] * (n + 1)
    for x in a:
        cnt[x] += 1

    import heapq

    heap = []
    for color in range(1, n + 1):
        if cnt[color]:
            heapq.heappush(heap, (-cnt[color], color))

    ans = []

    for i in range(m):
        shelf = [0] * s[i]

        for j in range(s[i]):
            if j >= d[i]:
                old = shelf[j - d[i]]
                if cnt[old] > 0:
                    heapq.heappush(heap, (-cnt[old], old))

            if not heap:
                print(-1)
                return

            negf, color = heapq.heappop(heap)
            shelf[j] = color
            cnt[color] -= 1

        for j in range(s[i], s[i] + d[i]):
            old = shelf[j - d[i]]
            if cnt[old] > 0:
                heapq.heappush(heap, (-cnt[old], old))

        ans.append(shelf)

    for shelf in ans:
        print(*shelf)

t = int(input())
for _ in range(t):
    solve()
```频率数组跟踪每种颜色剩余多少未使用的立方体。 

堆仅存储当前可用的颜色。 颜色在放置后立即从堆中消失。 它准确地再现`d_i`稍后的位置，这是通过重新插入位置的颜色来实现的`j - d_i`。 

一个微妙的细节是堆键使用当前剩余频率。 放置颜色后，其计数会减少，并且不会立即重新插入该颜色。 这可以避免频率过时。 

另一个重要的细节是完成架子后的清理循环。 某些颜色可能仍会被阻挡，因为架子在其冷却时间到期之前就结束了。 它们必须在开始下一个架子之前释放，因为架子是独立的。

 ## 边缘情况

 考虑：```
1
4 1
7 7 7 7
4
2
```放置第一个后`7`，颜色被阻挡在一个位置。 不存在其他颜色，因此可用集变为空。 算法立即返回`-1`，这是正确的。 

考虑：```
1
5 1
1 2 3 4 5
5
5
```每种颜色都出现一次。 堆永远不需要重用颜色。 任何订购都可以，并且色彩正好是货架长度。 

考虑：```
1
6 2
1 1 1 2 2 2
3 3
2 2
```第一个架子可能会消耗一些颜色副本`1`和`2`。 当架子结束时，在第二个架子开始之前重新插入块颜色。 这正确地反映了距离约束不会跨越货架边界。 第二个架子从全套剩余的合法颜色开始。
