 ## 解决方案
 ## 问题理解

 我们得到了一个完整的图表$n$顶点。 每个顶点最初都有一种颜色，颜色以整数形式给出。 图结构本身并不是我们需要显式操作的东西，因为每对顶点都是连接的。 

唯一可用的操作是选择一个其顶点当前共享相同颜色的连通子图，并将它们全部重新着色为任何其他颜色。 目标是使用最少数量的此类操作使每个顶点最终具有单一统一的颜色。 

因为图是完整的，所以任何顶点子集都是相连的。 这显着改变了问题：连通性并不限制我们可以选择哪些顶点，只是条件是所有选定的顶点当前必须具有相同的颜色。 

输入大小可达$10^6$，它立即排除任何二次方，例如尝试所有颜色对或重复模拟子集上的操作。 我们需要一个能够在线性时间内处理颜色数组的解决方案。 

一些微妙的情况很重要：

 如果所有顶点已经具有相同的颜色，例如：

 输入：```
5
3 3 3 3 3
```答案必须是 0，因为不需要任何操作。 任何盲目假设每种颜色至少执行一次操作的方法在这里都是错误的。 

如果所有颜色都是不同的，例如：```
4
1 2 3 4
```我们可能怀疑我们需要许多操作，但是因为我们可以一次对相同颜色的多个顶点重新着色，所以真正的答案仅取决于存在多少种不同的颜色，而不取决于$n$本身。 

关键的陷阱是过度考虑连通性。 由于图形是完整的，连接性永远不会限制我们，唯一真正的结构是颜色的分布方式。 

## 方法

 暴力解释将模拟该过程。 在每一步中，我们选择一些颜色类，选择它的一些子集，重新着色，更新图形，然后重复直到所有顶点共享一种颜色。 这在原则上是正确的，但它需要维护动态颜色组并重复扫描或更新顶点集。 在最坏的情况下，每个操作都可能触及$O(n)$顶点，我们最多可以执行$O(n)$操作，导致$O(n^2)$行为，这对于$n = 10^6$。 

关键的观察结果是，图的结构使得具有相同颜色的每组顶点都可以作为一个单元互换。 由于相同颜色顶点的任何子集都是连接的，因此我们可以将每个不同的颜色视为一个块。 更重要的是，我们可以通过将该颜色的所有顶点重新着色为某种目标颜色来一次性消除整个颜色。 

一旦明确了这一点，该过程就变得纯粹是组合的。 假设有$k$最初颜色不同。 我们选择其中一种作为最终目标颜色。 所有其他颜色类必须至少合并到其中一次，并且每个颜色类都可以在单个操作中合并。 这立即给出$k - 1$作为最佳答案。 

尝试对部分子集重新着色或进行中间转换没有任何好处，因为每个操作已经可以消耗整个颜色类而无需额外成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟|$O(n^2)$|$O(n)$| 太慢了|
 | 计算不同的颜色 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将问题简化为了解初始数组中存在多少种不同的颜色。 

1. 读取所有顶点颜色并将它们存储在列表中。 图的结构是无关紧要的，因为它是完整的，因此连通性对分组顶点没有任何限制。 
2. 计算数组中不同颜色的数量。 这可以在扫描一次数组时使用哈希集来完成。 这样做的原因是每种颜色都表现为一个独立的组，可以在单个操作中合并。 
3. 设不同颜色的数量为$k$。 如果$k = 1$，立即返回 0，因为图形已经是单色的。 
4.否则返回$k - 1$。 这相当于选择一种颜色作为最终目标并将所有其他颜色类别一一合并到其中。 

### 为什么它有效

 关键的不变量是，在该过程中的任何一点，每个剩余的颜色类都可以在单个操作中完全折叠为任何其他颜色。 因为颜色的任何子集都连接在一个完整的图中，所以我们决定消除的每种不同颜色永远不需要多个操作。 任何操作都不能将不同颜色的数量减少一个以上，除非将整个颜色类合并到另一个颜色类中，并且这种合并总是可能的。 这使得$k - 1$既必要又充分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    colors = list(map(int, input().split()))
    distinct = len(set(colors))
    print(max(0, distinct - 1))

if __name__ == "__main__":
    main()
```该解决方案读取颜色数组，将所有值插入到一个集合中以计算存在多少种唯一颜色，然后打印$k - 1$。 这`max(0, ...)`Guard 处理所有顶点已经共享相同颜色的简单情况。 

主要的微妙之处在于我们从不尝试模拟操作。 任何模拟都是不必要的，因为操作结构允许整个颜色类一步崩溃。

 ## 边缘情况

 当所有顶点共享相同颜色时，集合大小为 1，因此公式得出$1 - 1 = 0$。 该算法正确返回 0，无需超出最终结果的任何特殊分支`max(0, ...)`。 

当每个顶点都有不同的颜色时，设置的大小变为$n$，答案就变成了$n - 1$。 这与每个颜色类必须被吸收一次的事实相匹配，并且每次吸收都是一个有效的操作。 

当颜色以任意模式重复时，例如交替或聚集值，集合抽象会删除唯一性以外的所有结构。 由于操作仅取决于颜色标识而不取决于位置，因此这种简化对于所有配置仍然有效。
