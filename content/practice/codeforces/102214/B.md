 ## 解决方案
 ## 问题理解

 我们有一个正整数序列`a1, a2, ..., an`。 我们必须计算有序的位置对`(i, j)`，允许`i = j`，其中二项式系数

 [
 \binom{a_i}{a_j}
 ]

 很奇怪。 

顺序很重要，因为`(i, j)`和`(j, i)`是不同的对。 不同位置的相同值也会产生不同的对。 约束允许最多`10^6`测试用例中的元素，每个元素之间`1`和`10^6`，最多有 10 个测试用例。 官方声明给出了5秒的时间限制和512 MiB的内存限制。 

直接检查每对都需要`n^2`检查。 在`n = 10^6`， 那是`10^12`在考虑评估每个二项式系数的成本之前就对了。 这远远超出了 5 秒竞赛解决方案的能力，因此该解决方案必须避免单独查看配对。 

第一个微妙的情况是`i = j`。 例如，```
1
1
1
```有单对`(1,1)`， 和`C(1,1) = 1`，所以答案是`1`。 仅计算不同位置对的解决方案将错误地返回`0`。 

重复的值是另一个常见的错误来源。 为了```
1
3
1 1 1
```每一个`3 * 3 = 9`有序对有系数`C(1,1) = 1`，所以答案是`9`。 计算不同的值对而不是位置对会给出错误的结果。 该样本也出现在官方声明中。 

最后，`C(x,y)`为零时`y > x`，零是偶数。 例如，```
1
2
1 2
```有四个有序对。`C(1,1)`和`C(2,2)`是奇数，而`C(1,2)=0`和`C(2,1)=2`是偶数，所以答案是`2`。 如果粗心的解决方案将每对值都视为可能有效，而没有正确处理位条件，则此处将失败。 

## 方法

 蛮力方法是检查每个有序对`(i,j)`并判断是否`C(a_i,a_j)`很奇怪。 正好有`n^2`成对，所以最多`n = 10^6`有`10^12`迭代。 即使将奇怪的测试减少到恒定时间操作，这也已经太慢了。 

有用的观察是我们实际上不需要二项式系数的值。 我们只需要知道它是否是奇数。 这彻底改变了问题。 

对于两个非负整数`x`和`y`, 卢卡斯定理模 2 给出

 [
 \binom{x}{y} \equiv
 \prod_k \binom{x_k}{y_k} \pmod 2,
 ]

 哪里`x_k`和`y_k`是对应的二进制数。 二进制数字贡献`1`恰好在什么时候`y_k <= x_k`。 这样整个产品就是`1`正是当每设定位`y`也设置在`x`。 

按位表示法，

 [
 \binom{x}{y}\text{ 是奇数}
 \当且仅当
 (x\mathbin{&}y)=y。 
]

 所以原来的问题变得简单得多：对于每个数组元素`x`, 计算有多少个数组元素`y`是子掩码`x`。 

认为`freq[y]`是次数值`y`发生。 我们想要

 [
 \sum_x 频率[x]\sum_{y\subseteq x}频率[y]。 
]

 内部总和正是标准的子集求和 DP，通常称为 SOS DP。 而不是枚举每个的每个子掩码`x`，我们预处理每个掩码中包含的数组元素的数量。 

蛮力之所以有效，是因为检查一对在概念上很简单，但会失败，因为有平方数的对。 奇数二项式系数与子掩码关系完全对应这一观察结果让我们可以在可能的位掩码上用一个 SOS DP 来替换对枚举。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | 除了输入 | O(1) 太慢了 |
 | 最佳 | O(n + M log M) | O(n + M log M) | O(M)| 已接受 |

 这里`M`是严格大于最大数组值的最小的二的幂。 自从`a_i <= 10^6`，我们有`M <= 2^20 = 1,048,576`。 

## 算法演练

 1.读取数组并构建`freq[x]`，包含每个值的位置数`x`。 我们只关心实际发生的值，因此我们也记录最大值。 
2. 选择`M`作为大于最大值的二的最小幂。 每个可能的数组值都是一个掩码`[0, M)`。 
3.初始化一个数组`dp`和`dp[x] = freq[x]`。 在此刻`dp[x]`只计算精确出现的次数`x`，而不是它的子掩码。 
4. 独立处理每一位。 一会儿`b`，每个设置了该位的掩码都会从清除该位的相应掩码中接收计数：

 [
 dp[掩码] \mathrel{+}= dp[掩码\oplus 2^b]。 
]

 处理完前几位后，`dp[mask]`计算其已处理位形成子掩码的所有值`mask`。 处理完所有位后，`dp[x]`等于

 [
 \sum_{y\subseteq x}频率[y]。 
]

 这就是 SOS DP 不变量。 每个转换决定子掩码的特定位是零还是一，因此每个子掩码只包含一次。 

1. 迭代原始数组。 对于一个元素`x`， 有`dp[x]`职位`j`其价值`a_j`是一个子掩码`x`。 每个这样的位置给出一个奇二项式系数`a_i = x`。 
2. 添加`dp[x]`对于每个数组位置`i`。 重复值每次出现都必须处理一次，因为答案计算的是有序的位置对，而不是不同的值对。 

### 为什么它有效

 对于任意一对`(i,j)`， 让`x = a_i`和`y = a_j`。 根据卢卡斯定理模 2，`C(x,y)`当每组的位都是奇数时`y`也设置在`x`，这相当于`(x & y) == y`。 

SOS DP 保持了处理一组位后的不变量，`dp[x]`精确计算那些其处理位是相应位的子掩码的数组值`x`，而不受限制的位由稍后的转换处理。 处理完所有位后，`dp[x]`因此计算每个数组位置`j`满意的`(x & a_j) == a_j`。 

对于每个位置`i`，添加`dp[a_i]`因此准确计算有效位置`j`与`i`。 每个有效的有序对都被计数一次，无效的对不被计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        mx = max(a)
        size = 1 << mx.bit_length()

        freq = [0] * size
        for x in a:
            freq[x] += 1

        dp = freq[:]

        bit = 1
        while bit < size:
            block = bit << 1
            for start in range(0, size, block):
                end = start + bit
                for j in range(start, end):
                    dp[j + bit] += dp[j]
            bit <<= 1

        ans = 0
        for x in a:
            ans += dp[x]

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```频率数组直接由整数值索引。 由于最大值最多为`10^6`，它的二次方扩展最多有`1,048,576`条目。 

SOS 转换以块的形式写入。 对于一个长度的块`2 * bit`，前半部分表示当前位为零的掩码，后半部分表示当前位为 1 的掩码。 后半部分中的每个掩码都会从前半部分接收相应的值。 这避免了在最内层循环内进行额外的位测试，并且在 Python 中更加干净。 

循环停止时`bit == size`，因此掩码空间表示的所有二进制位置都被处理。 使用`mx.bit_length()`而不是总是固定 20 位，还可以使小型测试变得更加便宜。 

Python 整数不会溢出，这很重要，因为答案计算有序对并且可以达到`n²`， 或者`10^12`什么时候`n = 10^6`。 
保留原始数组，因为在 SOS DO 之后我们需要添加`dp[a_i]`每次出现一次。 仅使用频率数组并迭代不同的值需要分别乘以当前值的频率，这也是有效的，但保留数组使得与有序对的对应关系变得明确。

 ### 示例 1

 第一个官方样本包含两个测试用例。 对于第一个，数组是`[1, 5, 6]`。 相关的二进制表示是`001`,`101`， 和`110`。 

的子掩码`1`发生的只是`1`， 所以`dp[1] = 1`。 的子掩码`5`发生的情况是`1`和`5`， 所以`dp[5] = 2`。 的子掩码`6`发生的只是`6`，因为两者都没有`1`也不`5`是一个子掩码`6`。 

| 数组值`x`| 二进制`x`| 出现的子掩码 |`dp[x]`| 贡献|
 | ---| ---| ---| ---| ---|
 | 1 | 001| 1 | 1 | 1 |
 | 5 | 101 | 101 1, 5 | 2 | 2 |
 | 6 | 110 | 110 6 | 1 | 1 |

 总计为`1 + 2 + 1 = 4`，与官方输出匹配。 第二个示例案例包含三份副本`1`，所以每个有序对都是有效的，答案是`9`。 

### 示例 2

 对于```
1
2
1 2
```我们有二进制掩码`01`和`10`。 

最初，

 | 面膜|`freq`|
 | ---| ---|
 | 0 | 0 |
 | 1 | 1 |
 | 2 | 1 |
 | 3 | 0 |

 处理后位`0`， 面具`1`已经包含子掩码的计数`0`，和掩码`3`收到 mask 的贡献`2`。 处理后位`1`， 面具`3`收到口罩的捐款`1`和`2`。 

相关的最终值为：

 | 数组值`x`| 二进制`x`|`dp[x]`| 贡献|
 | ---| ---| ---| ---|
 | 1 | 01 | 1 | 1 |
 | 2 | 10 | 10 1 | 1 |

 答案是`2`。 这个例子证明了这样一个事实`1`不是子掩码`2`和`2`不是子掩码`1`，因此只有两个对角线对有贡献。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + M log M) | O(n + M log M) | 构建频率和求和答案的成本为 O(n)，而 SOS DP 执行`M/2`为每个添加`log₂M`位|
 | 空间| O(n + M) | 输入数组使用 O(n)，频率/DP 数组使用 O(M) |

 对于这个问题，`M <= 2^20`，所以 SOS 阶段的执行时间约为`20 * 2^19 = 10.5 million`最坏情况下的补充。 这是该解决方案符合 5 秒限制的关键原因，而`10^12`暴力配对检查不能。 官方限制为 5 秒和 512 MiB。

 ## 边缘情况

 对于自配对情况```
1
1
1
```频率阵列有`freq[1] = 1`。 只有一位需要处理，并且`dp[1]`遗迹`1`。 最终总和需要`dp[1]`一次，给予`1`。 该算法从不排除相等的位置，因此自然地处理对矩阵的对角线。 

对于重复值，```
1
3
1 1 1
```频率数组包含`freq[1] = 3`。 自从`1`是其自身的子掩码，SOS结果是`dp[1] = 3`。 三个位置中的每一个都添加`3`，生产`9`。 这正是有序位置对的数量。 

对于边界情况```
1
2
1 2
```这些值具有二进制形式`01`和`10`。 两者都不是另一个的子掩码。 两个自对有效，因为`x & x = x`，而两个交叉对无效。 最终的答案是`2`。 

对于诸如以下的值`7`，其二进制表示为`111`，每个较小的值`0`通过`7`是一个子掩码。 例如，与```
1
5
3 5 6 7 1
```有效的子掩码关系由 SOS DP 进行计数，而无需显式枚举它们。 价值`7`接受所有五个值，`5`接受`5`和`1`,`3`接受`3`和`1`,`6`只接受`6`， 和`1`只接受`1`。 贡献是`2 + 2 + 1 + 5 + 1 = 11`，所以测试块中的预期结果应该是`11`。
