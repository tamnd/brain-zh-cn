 ## 解决方案
 ## 问题理解

 我们给出了一个排列$a$尺寸的$n$，所以它是位置的双射$1 \ldots n$价值观$1 \ldots n$。 根据这个排列，我们定义了排列的变换：如果我们有两个排列$a$和$b$，然后应用$b$到$a$产生一个新的排列，其值在位置$i$是$a_{b_i}$。 换句话说，$b$不会按照通常的意义重新排序索引，它通过重新映射 _index_$b$，然后我们从中读取值$a$。 

然后我们定义一个递归过程，从$a$。 在第 0 步，结果是$a$。 在第 1 步中，我们结合$a$与自身使用相同的规则。 在步骤 2 中，我们再次将步骤 1 的结果与其自身相结合，依此类推。 后$x$我们获得的步骤$G(a, x)$，任务是有效地计算最终的排列，即使当$x$与$10^{10}$。 

关键约束是$n \le 10^5$，因此任何在每步线性时间内重复应用变换的方法一旦出现就变得不可能$x$很大。 递归的直接模拟呈指数增长，因为每一步都依赖于之前的完整排列，所以即使$O(n \cdot x)$已经不可行了，如果天真地实现递归结构，情况会更糟。 

出现微妙的边缘情况时$x = 0$，其中答案正是原始排列。 另一个重要的情况是当排列已经是恒等时。 在这种情况下，重复的自我应用总是会产生身份，但粗心的实现可能仍然会进行不必要的重新计算，并面临效率低下或索引假设不正确的风险。 

更结构化的边缘情况来自于正确理解索引。 由于排列中的值用作索引，因此很容易意外地将值视为从零开始或忘记它们仍在范围内$1 \ldots n$。 例如，如果$a = [2,1]$，然后应用一次运算给出$G(a,1)_1 = a_{a_1} = a_2 = 1$， 和$G(a,1)_2 = a_{a_2} = a_1 = 2$，所以结果仍然是$[1,2]$。 错误的索引约定会立即破坏这一点。 

## 方法

 蛮力的想法是从字面上遵循定义。 开始于$a$，并通过构建新数组来重复构建下一个排列$b$在哪里$b_i = a_{a_i}$，然后替换$a$和$b$，并重复这个过程$x$次。 每一步都需要$O(n)$，所以总成本是$O(n \cdot x)$。 自从$x$可以达到$10^{10}$，这种做法是完全不可行的。 

结构观察来自于注意到操作不是任意的重新计算，而是排列的组合。 如果我们解释一个排列$p$作为一个函数$p(i)$，那么变换$F(a,b)$正是函数组合：$F(a,b)(i) = a(b(i))$。 所以递归就变成了：$$G(a, x) = G(a, x-1) \circ G(a, x-1)$$这是反复的自作曲。 这就是关键：每一步都对组合下的排列进行平方。 

所以$G(a,1) = a \circ a = a^2$,$G(a,2) = a^2 \circ a^2 = a^4$，一般来说：$$G(a,x) = a^{2^x}$$这将问题从迭代平方转换为$x$乘以两个指数次方的排列的幂。 指数本身增长得非常快，但我们不需要将指数计算为 2 的幂； 相反，我们以不同的方式观察效果：每一步都使排列的“力量”加倍。 所以我们本质上是在计算$a$提高到$2^x$，但我们只需要通过对排列重复平方来模拟求幂，其中指数以二进制形式编码。 

最终的减少是我们需要计算排列指数，而不是指数$k$，我们有效地应用了加倍结构$x$次。 这可以使用二进制提升式预处理来完成：计算$a^{2^0}, a^{2^1}, \ldots, a^{2^{60}}$，然后根据二进制表示进行组合$x$。

 ## 算法演练

 我们将每个排列视为从索引到索引的函数。 我们重复应用的操作是函数复合，因此我们预先计算该函数的幂。 

1. 表示排列$a$作为一个函数$f$， 在哪里$f(i) = a_i$。 这使得构图定义明确，并避免值和位置之间的歧义。 
2. 预先计算一个表$up[k][i]$， 在哪里$up[k]$表示应用排列$2^k$次。 我们初始化$up[0] = a$。 这对应于该功能的一种应用。 
3. 对于每个$k > 0$， 建造$up[k]$通过作曲$up[k-1]$与自身：$up[k][i] = up[k-1][up[k-1][i]]$。 这是有效的，因为有两个应用程序$2^{k-1}$步骤等于$2^k$步骤。 
4.从身份排列开始$res(i) = i$，因为零应用程序什么也不做。 
5. 分解$x$成二进制形式。 对于每一位$k$在哪里$x$有1，申请$up[k]$按组合得到当前结果：$res(i) = up[k][res(i)]$。 这正好累计$x$应用程序。 
6.输出最终结果$res(i)$对于所有职位。 

为什么每个步骤都是必要的，来自于形成半群的置换组合的结构。 每个$up[k]$是一个预先计算的跳转宏操作$2^k$递归中的步骤，允许我们替换线性迭代$x$与对数分解。 

### 为什么它有效

 关键的不变量是$up[k]$总是表示之后获得的排列$2^k$原始变换的自我应用。 这对于$k = 0$根据定义。 假设它成立$k-1$，将其与自身组合给出两个连续的大小块$2^{k-1}$，它们一起精确地形成$2^k$应用程序。 由于排列的组合是结合的，分组的顺序不影响正确性，并且二元分解$x$确保我们准确地结合所需的权力。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    a = list(map(int, input().split()))
    x = int(input())

    LOG = x.bit_length() + 1

    up = [a[:]]
    for k in range(1, LOG):
        prev = up[k - 1]
        cur = [0] * n
        for i in range(n):
            cur[i] = prev[prev[i] - 1]
        up.append(cur)

    res = list(range(1, n + 1))

    k = 0
    while x > 0:
        if x & 1:
            new_res = [0] * n
            for i in range(n):
                new_res[i] = up[k][res[i] - 1]
            res = new_res
        x >>= 1
        k += 1

    print(*res)

if __name__ == "__main__":
    main()
```该实现以基于 1 的形式存储排列，因此每次访问都会在索引 Python 数组之前减一。 这可以避免意外的差一错误，否则会破坏合成。 

预处理循环通过重复地将前一层与其自身组合来构建排列的幂。 每个组合步骤都是应用两次变换的直接转换。 

最后一个循环应用二进制提升$x$。 我们不是从头开始重复重新计算，而是仅在设置相应位时应用预先计算的跳转，组成结果排列。

 ## 边缘情况

 当$x = 0$，算法永远不会进入二元提升循环并立即返回恒等排列。 例如，输入$a = [3,1,2]$,$x = 0$产生$[1,2,3]$，它符合定义，因为零应用意味着不会发生转换。 

当排列是恒等时，每个组合层都保持恒等。 在预处理中，将恒等式与自身组合再次产生恒等式，因此所有$up[k]$保持身份。 因此，最终结果始终是同一性，无论$x$，与多次组合身份不会改变任何内容的事实相匹配。 

对于循环排列，重复组合表现为循环的重复求幂。 例如$a = [2,3,1]$，应用一次轮换，两次返回同一性，并且更高的功率相应地交替。 提升结构正确地捕获了这一点，因为每个$up[k]$表示循环的精确幂，二进制分解可以重建正确的指数，而无需显式模拟中间步骤。
