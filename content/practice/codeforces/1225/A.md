 ## 解决方案
 ## 问题理解

 我们被要求构造两个正整数$a$和$b$使得它们恰好相差一个单位，即$a + 1 = b$。 我们没有得到这些数字本身。 相反，我们只给出了第一个数字$a$和第一个数字$b$。 任务是确定这样的对是否存在，如果存在，则在允许的范围内产生任何有效的对。 

关键的困难在于前导数字对数字的限制非常宽松。 许多数字共享相同的第一位数字，并且加一可以保留前导数字或显着改变它，特别是在十的幂上。 问题简化为查找是否存在至少一个整数$a$这样当我们加一时，结果的第一位数字就成为所需的数字。 

输出不需要是唯一的，这使我们能够搜索任何方便的构造，而不是精确或最小的构造。 

约束很小，两个数字都在$[1,9]$。 这立即排除了对复杂结构或搜索空间的任何需要。 即使对每个前导数字的一小部分代表性数字进行暴力破解也足够了。 然而，十进制表示的结构使得直接的建设性论证更加有效和清晰。 

当增量跨越十的幂边界时，会出现微妙的边缘情况。 例如，$199 + 1 = 200$将前导数字从 1 更改为 2。这是实现前导数字之间最有效转换的主要机制。 然而，并非所有数字转换都是可能的，有些数字对$(d_a, d_b)$无论大小如何，都不会在 +1 操作下发生。 

## 方法

 一个蛮力的想法是迭代所有数字直到$10^9$，检查第一个数字是$d_a$，并验证加一是否会产生第一个数字为$d_b$。 这是正确的，因为它直接测试定义，但这是不可行的，因为搜索空间包含多达十亿个候选。 

关键的观察是操作$a \to a + 1$仅以非常有限的方式更改前导数字。 前导数字唯一改变的时候是当进位传播通过一长串 9 时。 这意味着以下形式的数字$d_a99\ldots9$是唯一可以在递增后向上移动其前导数字的候选者。 尤其，$199 \to 200$,$2999 \to 3000$， 等等。 

这表明了一种建设性的策略。 我们尝试从最小可能的前缀匹配开始构建数字$d_a$，然后根据需要添加任意数量的 9，并检查加 1 是否会产生以$d_b$。 由于只有前导数字很重要，因此我们只需要测试尾随 9 的几个长度。 如果没有这样的建设工程，那么就不存在解决方案。 

这将问题从大量搜索减少到检查少数候选者。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(10^9)$|$O(1)$| 太慢了 |
 | 建设性检查 |$O(1)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 尝试建立候选编号$a$以数字开头的$d_a$。 最小的有意义的结构是一个以$d_a$接下来是一系列 9。 这是因为由 9 触发的进位是以受控方式更改前导数字的唯一方法。 
2. 对于尾随 9 的每个可能长度（从 0 到小常数，例如 9），构造$a = d_a$接下来是很多9。 这给了一个像这样的家庭$1, 19, 199, 1999, \ldots$。 
3. 计算$b = a + 1$。 增量将保留结构或触发增加前导数字的进位。 
4. 提取第一个数字$b$通过将其转换为字符串并读取第一个字符。 这直接对应了问题的要求。 
5. 如果第一个数字$b$比赛$d_b$,输出这一对$(a, b)$立即地。 
6. 如果所有尝试后都没有候选者成功，则输出$-1$。 

这样做的原因是任何有效的解决方案都必须涉及由 9 后缀引起的进位链。 如果存在一个解决方案，我们可以假设它的结构相当于某个带有前缀的数字$d_a$随后是足够的 9，以在递增时强制进行相同的前导数字转换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def first_digit(x):
    return int(str(x)[0])

def solve():
    da, db = map(int, input().split())

    for k in range(0, 10):
        a = int(str(da) + "9" * k)
        b = a + 1
        if first_digit(b) == db:
            print(a, b)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```实施直接反映了建设思想。 循环结束$k$从以下开始构建越来越大的数字$d_a$。 每个候选者都通过单个增量和对其第一位数字的恒定时间检查进行测试。 转换为字符串是安全的，因为构造的数字完全在范围内$10^9$问题所保证的界限。 

一个微妙的点是，我们并不尝试以数学方式优化数字提取。 这里的字符串转换足够快，因为循环运行了恒定的次数。

 ## 边缘情况

 一个关键的边缘情况是没有以以下开头的数字$d_a$可以产生一个以$d_b$递增后。 例如，$1 \to 3$失败是因为增量操作总是产生一个小的局部变化或产生数字 2 作为新的前导数字的进位。 

另一种情况是进位边界，例如$9 \to 10$。 这里，前导数字从 9 变为 1，这是以 10 为基数增量中唯一可能的重要环绕行为。 该算法显式测试$a = 9$，生产$b = 10$，并正确捕获前导数字变化。 

最后，长长的 9 链就像$1999 \to 2000$确认扩展数字不会改变进位传播后产生的前导数字。 不断增加的 9 数量的循环确保了如果有任何进位长度起作用，它就会被找到。
