 ## 解决方案
 ## 问题理解

 我们得到了一个正的目标数字$n$。 我们还固定一个整数$p$，它会移动以下形式的一系列数字$2^x + p$， 在哪里$x \ge 0$。 每个这样的值都是一个单独的“构建块”，我们可以多次重复使用同一个块。 

任务是表达$n$作为这些块的总和，同时使用尽可能少的块。 如果不存在这样的表示，我们必须报告这是不可能的。 

重新解释该结构的一个有用方法是扩展$k$选定的块：$$(2^{x_1} + p) + (2^{x_2} + p) + \dots + (2^{x_k} + p)$$这变成：$$(2^{x_1} + 2^{x_2} + \dots + 2^{x_k}) + k \cdot p$$所以这个问题相当于选择许多2的幂，其总和等于$n - k \cdot p$，同时也准确地使用$k$两个术语的权力。 

约束条件允许$n$最多$10^9$和$p$在一个小范围内。 这已经表明，任何依赖于枚举大型结构或对表示进行指数搜索的解决方案都将失败。 关键的观察是，二次方的结构极其严格，它们的任何和都由二进制表示控制。 

一种简单的方法会尝试通过贪婪地选择 2 的幂并进行调整来构建表示，或者尝试每个项数的可能指数的所有子集。 这失败了，因为即使将指数限制为$[0,30]$，组合数量呈指数增长。 

更微妙的失败案例来自于忽视可行性约束。 例如，如果$p$为正且大，选择太多项会使$k \cdot p$超过$n$，强制产生不能表示为 2 的幂和的负余数。 

## 方法

 蛮力的想法是固定被加数的数量$k$，然后尝试检查我们是否可以选择$k$指数$x_i$使得结果总和匹配$n$。 对于固定的$k$，这成为一个关于 2 的幂的划分问题，可以通过递归或子集构造来探索。 然而，即使对于单个$k$，配置的数量是巨大的，因为每个被加数独立地选择一个指数，导致指数搜索空间$k$。 尝试所有$k$最多$n$显然是不可行的。 

关键的简化来自于分离贡献$p$从二元结构来看。 一旦我们修好$k$，方程变为：$$\sum 2^{x_i} = n - k p = S$$所以我们只需要判断是否$S$可以精确地表示为$k$两个人的权力。 

二进制数的结构给出了两个事实。 形成所需的最少二的幂数$S$正是$\mathrm{popcount}(S)$，因为每个 1 位对应一个幂。 被加数的数量总是可以通过将二的幂分成两个较小的幂来增加，因此任何$k \ge \mathrm{popcount}(S)$只要我们不超过平凡的上限，就可以实现$k \le S$，因为每项的最小可能贡献是$1$。 

这将问题转化为可行性检查$k$，我们在那里寻找最小的$k$这样：$$S = n - k p \ge 0,\quad \mathrm{popcount}(S) \le k \le S$$我们可以利用较小的界限来代替代数求解$p$以及条件的平稳行为。 作为$k$生长，$n - k p$线性变化，并且 popcount 增长缓慢，因此检查有界范围$k$就足够了。 在实践中，尝试一切$k$最多几千个就足够了，因为任何有效的解决方案都必须在系统稳定到满足或违反约束的状态之前出现。

 ## 算法演练

 1. 迭代可能的被加数个数$k$，从 1 开始向上。 每个$k$表示假设我们准确地使用$k$p-二进制数。 
2. 对于每个$k$，计算剩余值$S = n - k \cdot p$。 这隔离了必须纯粹由二的幂形成的部分。 
3.如果$S < 0$，丢弃这个$k$，因为两个幂的和不能产生负值。 
4. 计算设置的位数$S$，表示为$\mathrm{popcount}(S)$。 这是形成所需的最小二的幂数$S$。 
5.检查可行性条件：我们需要$\mathrm{popcount}(S) \le k$，因为我们总是可以分割权力来增加任期数，并且$k \le S$，因为每一项至少贡献 1。 
6. 第一个$k$满足这两个条件就是答案。 
7. 如果没有$k$在测试范围内工作，输出$-1$。 

核心不变量是每次我们测试一个固定的$k$，我们将问题简化为纯二元分解问题。 popcount 条件捕获了不可约结构$S$，并且拆分保证我们总是可以在不改变总和的情况下增加项数。 这意味着可行性仅取决于是否$k$位于可实现的最小和最大分解尺寸之间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def popcount(x):
    return x.bit_count()

def solve():
    n, p = map(int, input().split())

    # Try possible number of summands
    for k in range(1, 2001):
        S = n - k * p

        if S < 0:
            continue

        if popcount(S) <= k <= S:
            print(k)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```代码直接实现了导出的可行性条件。 循环结束$k$是有界的，因为有效解总是出现在任一解之前的小范围内$S$变为负值（当$p > 0$）或者 popcount 约束变得简单地满足（当$p < 0$）。 使用`bit_count()`干净地隔离二进制结构，避免手动位操作。 

双重不平等`popcount(S) <= k <= S`是核心正确性条件，可防止分解不足和不可能的过度分解。

 ## 边缘情况

 当$p = 0$，问题简化为表达$n$作为具有最小计数的二的幂的和。 该算法立即检查$k = \mathrm{popcount}(n)$， 自从$S = n$，这是最小的可行值。 

什么时候$p > 0$，增加$k$减少$S$。 最终$S$变为负数且全部变大$k$均无效。 该算法自然会跳过这些情况，只评估有意义的前缀$k$。 

什么时候$p < 0$，增加$k$增加$S$，使得 popcount 约束更容易满足。 第一个可行的$k$发生在$k$超过了固有的二进制复杂度$S$，并且循环在边界之前尽早捕获此转换$S \ge k$变得相关。
