 ## 解决方案
 ## 问题理解

 我们收到了连续几天的电视节目时间表。 每天只播放一个节目，如果我们购买某个节目的订阅，我们就可以访问整个时间线的所有剧集。 

任务不是覆盖所有日期，而是选择一组节目，使得至少存在一个连续的块`d`该区块中出现的所有节目都包含在我们购买的节目中的天数。 我们希望尽量减少我们订阅的不同节目的数量，以使这样的块成为可能。 

另一种查看方式是我们可以选择一个长度的窗口`d`，对于该窗口，我们必须确保其中的所有不同值都被我们选择的集合“覆盖”。 在选择集合后，我们可以自由选择最佳窗口，因此最佳策略取决于找到一个不同计数最小的窗口。 

限制很小：`n ≤ 100`每个测试用例和总计`n`跨测试也≤ 100。这意味着`O(n^2)`甚至`O(n^3)`解决方案是可以接受的，我们可以安全地显式检查每个窗口，而不必担心性能。 

当每个窗口中的所有元素都不同时，就会出现微妙的边缘情况。 在这种情况下，答案就变成了`d`，因为任何大小的窗口`d`迫使我们订阅所有内容`d`显示。 另一种边缘情况是节目大量重复，因此窗口仅包含一个不同的节目。 那么答案就变成 1，因为购买那个单场演出就足以满足该窗口的需要。 

一个天真的错误是认为我们必须全局最小化整个数组中的不同显示。 这是不正确的，因为该要求仅适用于一个选定的窗口，而不是整个时间表。 

## 方法

 直接的暴力方法是考虑每个连续的长度段`d`。 对于每个片段，我们计算其中出现了多少个不同的节目。 如果我们购买这些节目的订阅，我们就可以观看该片段，因此该片段所需的订阅数量就是其不同的计数。 我们在所有细分市场中取最小值。 

这是有效的，因为所选的片段准确地决定了我们必须订阅的节目。 然而，如果不小心，从头开始重新计算每个段的不同计数会导致效率低下，因为每个窗口都可能花费`O(d)`并且有`O(n)`视窗。 

关键的观察是我们不需要任何全局结构或高级数据结构。 自从`n`很小，即使为每个窗口重新计算频率图也足够快。 或者，我们可以维护一个滑动窗口频率表并在`O(1)`每一步，但这不是必需的。 

使这个问题变得简单的结构是，决策完全是本地于窗口的，并且除了取最小值之外，不同窗口之间没有交互。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（每个窗口重新计算）| O(n·d) | O(k) | 已接受 |
 | 滑动窗口频率| O(n) | O(k) | 已接受 |

 ## 算法演练

 我们迭代一个长度的所有可能的起始位置`d`分段并计算其中不同元素的数量。 

1. 对于每个测试用例，请阅读`n`,`k`， 和`d`，以及一系列的节目。 
2. 对于每个索引`i`从`0`到`n - d`，考虑段`[i, i + d - 1]`。 这代表我们可能希望通过订阅“支持”的连续几天的可能块。 
3. 对于每个段，使用集合或频率数组计算其中出现的不同值的数量。 此计数表示如果我们选择此片段，我们必须订阅的节目数量。 
4. 跟踪所有段的最小此类不同计数。 
5. 输出该最小值。 

关键思想是，一旦我们修复了一个片段，就会强制使用最小订阅集：它正是该片段中不同节目的集合。 订阅该片段之外的任何节目没有任何好处，因为它无助于满足该特定块的条件。 

### 为什么它有效

 对于任何选定的长度段`d`，我们必须能够观看它的所有日子。 由于订阅包括节目的所有剧集，因此唯一的要求是该片段中出现的每个节目都包含在我们购买的剧集中。 因此，固定段的最佳集合正是其不同的元素。 由于我们可以选择最佳分段，因此最终答案是所有分段的最小不同计数。 这确保我们不会过度计数或考虑数组的不相关部分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k, d = map(int, input().split())
    a = list(map(int, input().split()))

    ans = float('inf')

    for i in range(n - d + 1):
        seen = set()
        for j in range(i, i + d):
            seen.add(a[j])
        ans = min(ans, len(seen))

    print(ans)
```核心循环检查每个可能的长度窗口`d`。 在每个窗口内，我们构建了一组遇到的节目。 如果我们选择该窗口，该集合的大小正是所需的订阅数量。 

的初始化`ans`因为无穷大确保任何有效的窗口都可以改进它。 由于约束很小，每次重建集合就足够了，并且避免了维护增量状态的复杂性。

 ## 边缘情况

 完全均匀的数组显示了最简单的结构。 每个窗口都包含一个值，因此算法始终返回 1，这与订阅一个节目就足够的事实相匹配。 

完全不同的数组强制每个长度的窗口`d`准确地有`d`独特的表演。 该算法正确地反映了这一点，因为集合大小等于`d`对于每个细分市场。 

交替或周期性序列等重复模式证实重叠窗口不会影响正确性，因为每个窗口都是独立评估的，只有其内部不同的集合才重要。
