 ## 解决方案
 ## 问题理解

 我们有一排门必须从左到右打开。 门`i`有成本和回报。 要正常打开一扇门，我们目前必须至少有它的金币成本，然后我们支付成本并获得奖励。 只有在之前的所有门都打开之后，才能打开一扇门。 

在开始之前，我们可以选择一些门并取下它们的锁。 移除锁后，门可以自由打开，但每个移除的锁都算作一次操作。 目标是使所有门均可到达，同时使用尽可能少的操作。 

输入给出了几个测试用例。 每个测试用例包含门的数量、初始硬币数量、每扇门的成本以及从每扇门获得的奖励。 输出是必须拆除锁的门的最小数量。 

约束足够小以允许动态编程。 门的数量最多为 100 个，所有硬币的值也最多为 100 个。由于每打开一扇门最多可以增加 100 个硬币，因此打开所有门后最大可能的硬币数量约为`100 + 100 * 100 = 10100`。 这意味着基于当前硬币数量的状态空间是可行的。 尝试移除门的所有可能子集的解决方案需要`2^n`选择，即使对于`n = 100`。 

棘手的情况来自这样一个事实：拆锁不仅在门无法打开时才有用。 目前价格实惠的门可能仍然值得免费制作，因为节省成本可以增加以后可用的硬币数量。 

例如：```
Input
3 10
5 9 9
1 2 9
```正确的输出是：```
2
```贪婪的方法可能会正常打开第一扇门，因为 10 个硬币就足够了。 打开后我们有`10 - 5 + 1 = 6`硬币，无法打开第二扇门。 我们需要拆掉第二扇门，后来仍然买不起第三扇门。 拆除第一扇门也是必要的。 错误在于假设一扇负担得起的门应该总是正常打开的。 

另一种边界情况是不需要任何操作时：```
Input
1 1
1
1
```答案是：```
0
```唯一的门可以立即打开，因此任何强制至少移除一把锁的方法都是错误的。 

## 方法

 直接的暴力方法是尝试移除所有可能的门组。 对于每个子集，我们模拟从第一扇门到最后一扇门的过程。 如果门锁着，我们会检查是否有足够的硬币。 如果不是，则所选子集失败。 否则，我们继续并更新硬币计数。 在所有成功的子集中，我们采用最小的尺寸。 

这是正确的，因为已检查了移除门的所有可能选择。 问题是子集的数量。 和`n = 100`， 有`2^100`可能的选择，这远远超出了可以处理的范围。 

有用的观察是我们不需要准确记住哪些门被移除。 未来只取决于两件事：我们即将打开哪扇门以及我们目前拥有多少代币。 如果我们以两种不同的方式用相同数量的硬币到达同一扇门，那么更好的状态总是操作次数较少的状态。 这让我们可以将多种可能性合并到一个动态编程状态中。 

对于每扇门，有两个过渡。 我们可以解除它的锁定，不支付任何硬币，获得奖励，并添加一个操作。 或者我们可以保留锁，但前提是我们现有的硬币足够。 我们付出成本，获得回报，并保持相同的操作次数。 

状态计数是可控的，因为硬币范围大约为 10100，每个测试用例大约有 100 万个状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(1) | O(1) | 太慢了|
 | 最佳| O(n * n * 最大硬币数) | O(最大币数) | 已接受 |

 ## 算法演练

 1. 创建一个动态规划数组，其中`dp[c]`表示打开已处理的门前缀后所需移除的锁的最少数量，并以恰好结束`c`硬币。 

价值`c`描述了过去所需的一切。 一旦知道当前的硬币数量，先前选择的顺序就不再重要。 

1. 打开任何门之前初始化状态。 我们有起始数量的硬币并且已经移除了零锁，所以初始状态是`dp[starting_coins] = 0`。 
2. 从左到右处理门。 对于每个可能的当前硬币数量，尝试取下当前门的锁。 

新的金币数量就变成了当前的金币加上这扇门的奖励，因为没有花任何金币。 操作次数加一。 

1.对于同一扇门，如果当前的币值至少是门的成本，则尝试保持锁定。 

转变减去成本，然后加上奖励。 操作计数不变。 

1.处理完所有门后，答案是所有可达硬币状态中的最小值。 

可能有多种可能的最终硬币数量。 我们只关心其中最少数量的操作。 

为什么它有效：

 不变的是，在处理任何门前缀之后，每个可到达的硬币数量都与到达它所需的移除锁的最小数量一起存储。 这两个转换涵盖了隔壁的所有可能的决定：要么拆掉它的锁，要么保留它并正常付款。 由于每个有效的决策序列都被表示，并且相同状态的更差版本被丢弃，所以最终的最小值正是最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    INF = 10**9
    MAX_C = 10100

    for _ in range(t):
        n, x = map(int, input().split())
        c = list(map(int, input().split()))
        a = list(map(int, input().split()))

        dp = [INF] * (MAX_C + 1)
        dp[x] = 0

        for i in range(n):
            ndp = [INF] * (MAX_C + 1)

            for coins in range(MAX_C + 1):
                if dp[coins] == INF:
                    continue

                free_coins = coins + a[i]
                if free_coins <= MAX_C:
                    if dp[coins] + 1 < ndp[free_coins]:
                        ndp[free_coins] = dp[coins] + 1

                if coins >= c[i]:
                    normal_coins = coins - c[i] + a[i]
                    if normal_coins <= MAX_C:
                        if dp[coins] < ndp[normal_coins]:
                            ndp[normal_coins] = dp[coins]

            dp = ndp

        out.append(str(min(dp)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```数组`dp`存储每种可能数量的硬币的当前最佳答案。 初始状态将零操作置于起始量。 

对于每扇门，都会创建一个新的数组，因为所有转换都必须使用打开当前门之前的状态。 重复使用相同的数组将允许在一次迭代中多次打开同一扇门。 

第一个转换对应于移除锁。 它始终存在，因为移除的锁不需要任何硬币。 第二个转变对应的是正常开放，只有足够的硬币才允许。 

最大硬币价值是固定的，因为最大可能的起始值为 100，并且 100 扇门中的每一扇最多可以添加 100 个硬币。 使用这个固定界限可以避免不必要的内存开销并保持实现简单。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n * 最大硬币数) | 每扇门都会处理一次所有可能的硬币数量 |
 | 空间| O(最大币数) | 仅存储当前和下一个 DP 数组 |

 最大硬币价值约为 10100，因此每个测试用例的转换总数约为 100 万个。 这很容易符合限制。 

## 测试用例```python
import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline

    t = int(data())
    ans = []
    INF = 10**9
    MAX_C = 10100

    for _ in range(t):
        n, x = map(int, data().split())
        c = list(map(int, data().split()))
        a = list(map(int, data().split()))

        dp = [INF] * (MAX_C + 1)
        dp[x] = 0

        for i in range(n):
            ndp = [INF] * (MAX_C + 1)
            for coins in range(MAX_C + 1):
                if dp[coins] == INF:
                    continue

                if coins + a[i] <= MAX_C:
                    ndp[coins + a[i]] = min(ndp[coins + a[i]], dp[coins] + 1)

                if coins >= c[i]:
                    ndp[coins - c[i] + a[i]] = min(ndp[coins - c[i] + a[i]], dp[coins])

            dp = ndp

        ans.append(str(min(dp)))

    sys.stdin = old
    return "\n".join(ans)

 ## 边缘情况

 对于这个案例：```
3 10
5 9 9
1 2 9
```该算法开始于`dp[10] = 0`。 对于第一扇门，它保留了两种可能性：正常打开留下 6 个硬币，而解锁一次操作留下 11 个硬币。 第二条路径是唯一可以有效地穿过所有门的路径。 最终的最小操作次数为`2`。 

对于这个案例：```
1 5
10
10
```唯一的初始状态有 5 个硬币。 通常打开是不可能的，因为成本是 10。解除锁定的转换会创建一个最终状态，需要 15 个硬币和一次操作，给出正确的答案。 

对于每扇门都可以承受的情况，例如：```
5 100
100 100 100 100 100
1 1 1 1 1
```DP始终保持零操作路径。 该算法不会仅仅因为不必要的锁可以删除而删除它们。 最小值保持为零。
