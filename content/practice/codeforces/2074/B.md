 ## 解决方案
 ## 问题理解

 我们从一个正整数数组开始。 当剩下的数字不止一个时，我们选择两个值，用一个新的正整数替换它们$x$，并要求三个长度形成一个非退化三角形。 

对于两侧$a$和$b$，三角不等式告诉我们第三条边必须满足$$|a-b| < x < a+b.$$自从$x$必须是整数，最大可能的选择始终是$$x = a+b-1.$$这一过程一直持续到只剩下一个数字为止。 我们的目标是最大化最终数字。 

约束足够大，我们需要一个非常简单的解决方案。 所有测试用例的数组元素总数最多为$2 \cdot 10^5$，这意味着$O(n)$或者$O(n \log n)$每个测试用例的算法很容易足够快。 任何试图探索不同合并顺序的方法都将变得不可行，因为可能的操作序列的数量呈指数增长。 

主要的挑战是认识到，一旦我们了解每次操作会损失多少价值，确切的合并顺序并不重要。 

一些边缘情况很容易被忽略。 

考虑单个元素：```
1
10
```没有执行任何操作，所以答案很简单`10`。 盲目应用涉及合并次数的公式的解决方案可能会意外修改该值。 

考虑两个要素：```
2
5 7
```最大的有效替换是$5+7-1=11$，所以答案是`11`。 对三角不等式的粗心解释可能会错误地允许$x=12$，但这会创建一个退化三角形。 

考虑所有：```
3
1 1 1
```第一次合并给出$1+1-1=1$。 再次合并给出$1+1-1=1$。 答案是`1`。 此示例表明，每次合并都必然会从总和中丢失一个单位。 

## 方法

 暴力解决方案将在每一步尝试每一个可能的对以及每一个有效值$x$。 由于每个操作都会改变数组的状态，因此可能的序列数量会以组合方式爆炸。 即使对于小$n$，搜索树变得巨大。 这种做法是完全不切实际的。 

要找到模式，请关注数组总和发生的情况。 

假设我们合并值$a$和$b$。 为了最大化最终答案，我们应该明确选择最大的有效替换：$$x=a+b-1.$$在操作之前，这两个元素贡献$a+b$至总和。 

手术后，他们贡献$a+b-1$。 

总和正好减少一。 

这个观察就是整个问题。 

每个操作都会从数组中删除一个元素，因此减少了数组的大小$n$尺寸$1$准确地要求$n-1$合并。 

由于每次合并都会将总和减少一，因此最终值必须是$$\left(\sum a_i\right) - (n-1).$$别的都无所谓。 合并顺序是无关紧要的，因为每个最佳合并都会丢失一个单元，并且总是存在精确的$n-1$合并。

 ## 算法演练

 1. 读取数组并计算其总和$S$。 
2.让$n$是元素的数量。 
3. 观察每个最佳合并替换$a$和$b$和$a+b-1$。 
4. 每次这样的合并都会使总和恰好减少 1。 
5. 减少$n$元素到一个元素需要精确$n-1$合并。 
6.全部合并后，最终值等于$$S-(n-1).$$1. 输出该值。 

### 为什么它有效

 一对的最大可能替代品$(a,b)$是$a+b-1$，因为非退化三角形的第三条边必须严格小于$a+b$。 任何较小的选择只会减少未来的可能性，因此每个最优策略都会选择$a+b-1$。 

每个最佳合并都会将数组总和减少一。 由于合并次数固定为$n-1$，总减少量也固定为$n-1$。 最终数组包含一个值，其值等于原始总和减去总减少量。 任何合并顺序都不会产生不同的结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ans.append(str(sum(a) - (n - 1)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```实现直接遵循数学观察。 

数组的总和计算一次。 因为每次合并都会将总和减少一并且恰好$n-1$发生合并，我们减去$n-1$从总数。 

不存在棘手的边界条件。 什么时候$n=1$，公式变为$$\text{sum}(a)-0,$$它正确返回原始值。 Python 整数很容易处理最大可能的总和，因此溢出不是问题。

 ## 边缘情况

 考虑尽可能最小的数组：```
1
10
```该算法计算：$$10-(1-1)=10.$$没有发生合并，与真实流程完全匹配。 

考虑两个要素：```
2
5 7
```该算法计算：$$12-1=11.$$直接模拟还给出$5+7-1=11$。 这证实了严格的三角不等式被正确处理。 

考虑所有：```
3
1 1 1
```该算法计算：$$3-2=1.$$手动跟踪给出：$$(1,1)\rightarrow 1,$$然后$$(1,1)\rightarrow 1.$$最后的值又是`1`。 这证明了每次合并都会使总和恰好减少 1 的不变性。 

考虑高度不均匀的值：```
3
1 1000 1
```该算法计算：$$1002-2=1000.$$一种最佳序列是：$$1+1-1=1,$$离开`[1000, 1]`。 

然后：$$1000+1-1=1000.$$最终值为`1000`，完全符合公式。 这证实了结果仅取决于总和和合并次数，而不取决于合并顺序。
