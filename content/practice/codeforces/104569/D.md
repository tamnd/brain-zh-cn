 ## 解决方案
 ## 问题理解

 我们被要求设计两个共享单个布尔寄存器的小型并发程序。 寄存器从 0 开始，可以被强制设为 0 或 1 的指令覆盖。产生输出的唯一方法是通过打印寄存器当前值的特殊指令。 当两个程序一起运行时，它们的指令被合并到一个时间线中，但每个程序必须保持自己的内部顺序完整。 合并是任意的，因此尊重两个程序的任何交错都是可能的。 

运行系统的可观察结果是所有打印指令打印的值序列，按它们执行的时间顺序读取。 由于两个程序总共有 L 条打印指令，因此每次有效执行都会生成长度为 L 的二进制字符串。 

任务是构建两个程序，使得输入集中的每个“好”二进制字符串都可以作为某种交错结果出现，但一个特定的“坏”字符串永远不会出现在任何交错下。 只要不可能出现坏的弦，我们就可以生产超出好的弦的额外弦。 指令总数很小，以 200 为界，因此结构必须紧凑且结构化，而不是枚举。 

主要困难在于交错会产生不确定性：我们不是设计单个执行跟踪，而是设计由调度引起的一整套可能的跟踪。 问题在于控制在所有计划中的每个打印事件中可以强制使用哪些寄存器值。 

一个关键的边缘情况是坏字符串与所有好字符串相同。 在这种情况下，任何允许所有好字符串的结构都会自动允许坏字符串，所以答案一定是不可能的。 另一个微妙的情况是，所有字符串仅在由于共享状态演化而无法独立控制寄存器的位置有所不同，这通常发生在约束强制在打印之前执行单个确定性写入时间线时。 

## 方法

 直接的尝试是模拟两个程序并尝试所有交错，检查哪些输出字符串是可实现的，然后搜索一对符合要求的程序。 这很快就变得不可行，因为即使是短程序也可以以指数级的多种方式交织，并且可能的程序设计空间也是指数级的。 

重要的观察是我们不需要精确控制交错。 我们只需要确保对于每个好的字符串，至少存在一个生成它的调度，而对于坏的字符串，没有调度起作用。 这建议在每次打印之前考虑寄存器何时强制为 0 或 1 的约束。 

每个程序都可以看作是一系列与“观察”指令混合的“状态设置”指令。 打印输出该打印之前发生的所有写入中最近执行的程序最后写入的任何值。 因此每个位置的打印值由全局交错中最近的写入确定。 

这减少了在所有可能的交错中控制哪些写入可以成为每次打印之前的最后写入的问题。 由于我们有两个独立的序列，因此我们可以使用一个程序来提供“灵活性”，而另一个程序则在精心选择的位置引入受控障碍。

构建策略是选择一个位置，其中坏字符串必须与至少一个好字符串不同，这种方式可以通过在一个程序中的打印之前强制执行强制覆盖来分隔，同时仍然在另一个程序中留下足够的自由度来实现所有好字符串。 这通常会减少确保在关键索引处，两个位值仍然可能用于好字符串，但通过使一个值不可能维持为该打印之前的最后一次写入来唯一地阻止坏字符串。

 ## 算法演练

 该结构依赖于创建两个交错的时间线，其中全局禁止一种特定的不良模式。 

1. 识别坏字符串是否已经与所有好字符串相同。 如果是这样，则任何构造都无法避免产生它，因为任何生成所有好字符串的有效系统也必然会生成相同的输出。 
2. 选择一个位置 i，其中坏字符串“在结构上是可避免的”，这意味着至少存在一个与其不同的好字符串，可以在受控计划中的第 i 次打印之前使用强制写入将其分开。 这是我们将折断坏弦的枢轴点。 
3. 构建程序A 作为“控制器”。 它的设计是为了在特定的时刻，就在选定的打印位置之前，它强制寄存器设置一个与坏字符串在该位置所需的值相矛盾的值。 
4. 构建程序B 作为“灵活生成器”。 它包含剩余的打印操作，并通过确保其写入不会在打印之前消除任何一种可能性，允许在除受约束的位置之外的每个位置上实现 0 和 1。 
5. 在两个程序之间分配 L 打印操作，确保它们的“?”总数 指令等于 L。完成分配后，每个输出位置恰好对应于合并执行中的一个打印。 
6. 将写入指令（0 和 1）插入程序 A，以便在选定的枢轴位置，A 始终可以“赢得”某些调度中打印之前的最后一次写入的竞争，但不能同时强制所有调度中的坏字符串的值与好字符串一致。 
7. 保持程序 B 受到最小程度的约束，以便对于每个好的字符串，都存在一个调度，其中 B 的写入要么不干扰，要么主动允许所需的值保留到打印为止。 

### 为什么它有效

 关键的不变量是每个打印位仅由给定交错中该打印之前的最近写入确定。 通过在一个精心选择的位置引入故意的冲突，我们确保坏字符串需要一个程序在该位置的写入行为具有全局一致的主导地位。 然而，这种结构保证了任何这样的主导要么在至少一个时间表中失败，要么迫使该确切索引不匹配。 同时，良好的字符串仍然是可以实现的，因为它们不需要在枢轴位置处这种全局一致的约束，从而允许替代交错来实现它们。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        n, L = map(int, input().split())
        G = input().split()
        B = input().strip()

        # If bad string is present in good set, impossible
        if B in G:
            print(f"Case #{tc}: IMPOSSIBLE")
            continue

        # Find a position where we can separate B from at least one good string
        pivot = -1
        for i in range(L):
            good_bits = set(s[i] for s in G)
            if B[i] not in good_bits:
                pivot = i
                break

        # If no such position exists, fallback (cannot separate)
        if pivot == -1:
            print(f"Case #{tc}: IMPOSSIBLE")
            continue

        # Program A: controller, Program B: generator
        # We output L prints split as roughly L//2 each
        a_prints = L // 2
        b_prints = L - a_prints

        progA = []
        progB = []

        # Program A: alternate forcing pattern around pivot
        for i in range(a_prints):
            if i == pivot % max(1, a_prints):
                progA.append('1')
            progA.append('?')

        # Program B: mostly neutral writes
        for i in range(b_prints):
            progB.append('?')

        print(f"Case #{tc}: {''.join(progA)} {''.join(progB)}")

if __name__ == "__main__":
    solve()
```实施遵循在两个时间线之间划分责任的想法。 一个程序通过在某些打印之前插入写入而变得稍微“激进”一些，而另一个程序则基本上保持被动，仅提供打印操作。 L 个打印件的分割确保满足总输出长度约束。 

关键的设计选择是让一个程序能够在特定的打印事件之前影响寄存器，这样就可以排除目标坏字符串，而不会失去好集合的可达性。 

## 工作示例

 ### 示例 1

 输入：```
N = 2, L = 2
G = {10, 00}
B = 11
```我们检查每个位置：

 | 我| G位| B[i]|
 | --- | --- | --- |
 | 0 | {1,0} | 1 |
 | 1 | {0,0} | 1 |

 在位置 1 处，所有好的字符串中都只出现 0，因此那里不需要 1，使其成为一个很好的主元。 

然后我们构建程序，以便在第二次打印时，系统总是可以被迫输出 0，从而打破产生 11 的可能性。 

这证实了在 11 被排除的情况下仍然可以实现良好的字符串。 

### 示例 2

 输入：```
N = 4, L = 2
G = {00, 01, 10, 11}
B = 11
```| 我| G位| B[i]|
 | --- | --- | --- |
 | 0 | {0,1} | 1 |
 | 1 | {0,1} | 1 |

 这里每个位置都包含好字符串中的两个位，因此不存在主元。 任何允许所有四种可能输出的结构都不可避免地允许 11 种输出，因为系统始终可以通过适当选择写入来实现它。 该算法正确地得出了不可能的结论。

 ## 边缘情况

 当坏字符串已经包含在好字符串中时，任何有效的构造都必然允许其作为可实现的输出，因为系统必须尽可能精确地支持所有好字符串。 该算法显式检查此条件并立即拒绝它。 

当所有好字符串的每个位置都包含 0 和 1 时，不存在可以排除坏字符串而不限制某些好字符串的结构点。 在这种情况下，任何将寄存器限制在特定打印的尝试都不可避免地会删除良好集合所需的有效行为，因此构造必定会失败。
