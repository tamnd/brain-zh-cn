 ## 解决方案
 ## 问题理解

 我们获得了一系列课程，这些课程构成了先决条件森林。 每门课程都有一个先决条件，或者根本没有先决条件。 这保证了该结构是有根树的有向森林，其中边从节点指向其父节点。 

完成学位的有效方法是尊重先决条件的所有课程的任何线性顺序，这意味着每门课程都在其先决条件之后出现。 由于每门课程只进行一次并且没有循环，因此有效顺序正是该森林的拓扑排序。 

每门课程都有一个字母标签，任何有效的排序都会通过按课程学习顺序写下这些字母来生成一个字符串。 在所有有效的拓扑顺序中，我们不需要提供结果字符串的分布，而是要求给定模式作为子字符串出现在生成的字母序列中的概率。 

关键的困难在于不同的拓扑顺序是指数级的，并且它们会导致不同的字母序列。 我们必须隐含地对所有这些进行推理。 

输入量较小，最多 100 个课程，最多 5 个模式。 这强烈表明我们可以在子集上提供指数状态空间，但不能直接在排列上提供指数状态空间。 对所有有效拓扑顺序的简单枚举已经是不可行的，因为即使是 100 个节点的森林也可以生成阶乘许多线性扩展。 

一个微妙的边缘情况来自于相同的字母。 两个不同的课程可以在最终字符串中产生相同的字符，因此计算子字符串的出现次数取决于实际的课程顺序，而不仅仅是字符多重集。 这使得不可能将问题减少到计算不同的字符串。 

当某个模式在单个序列中多次出现时，就会出现另一种边缘情况。 我们被要求提供一个二元事件，它是否至少出现一次，而不是它出现多少次。 这改变了我们跟踪模式匹配状态的方式，因为重复的匹配不应该被重复计算。 

## 方法

 一个强力的想法是生成森林的所有有效拓扑顺序，并根据每个模式检查每个结果字符串。 森林中的有效阶数大约是子树大小的阶乘的乘积，在最坏的情况下，当图没有边时，它会退化为 N 阶乘。 当N达到100时，即使枚举10^20个序列也是不可能的。 

森林的结构表明了一代人的控制力更强。 在任何时候，下一个选择的课程都必须是已经完成先决条件的课程。 这是一个经典的拓扑 DP 状态：我们可以将已完成的课程集表示为位掩码，并维护当前的可用根集。 然而，直接迭代所有掩码仍然会给出 2^N 个状态，并且对于每个状态，转换最多 N 个选择，这已经是边界，但在 Python 中只有经过大量修剪才可能可接受。 真正的问题是，我们还需要跟踪每个部分排序是否已经与每个模式作为子字符串匹配，这引入了一个额外的类似自动机的维度。 

关键的观察结果是模式很短，最多长度为 20。我们可以使用类似于 Aho-Corasick 的自动机仅跟踪模式匹配的进度，而不是跟踪完整的字符串。 每个部分序列可以通过每个模式的当前自动机状态来概括。 然而，独立跟踪所有模式似乎仍然很昂贵。

关键的结构简化来自于逆向视角：我们不是构建完整的序列，而是对已完成课程的子集执行DP，并且对于每个状态，我们维护由部分序列引起的自动机状态的概率分布。 因为 M ≤ 5，我们可以将组合自动机状态维护为模式进度状态的元组。 每个状态转换仅依赖于附加一个字母，因此我们可以增量更新自动机状态。 

第二个关键思想是使用 DP 在具有可用节点边界的子集上计算拓扑顺序上的概率分布。 对于每个子集，我们在当前可用课程集上维护一个 DP，这些课程是满足先决条件的课程。 

我们将这些想法结合到子集上的 DP 中，其中转换对应于选择一个可用节点，并且我们传播路径计数和模式匹配自动机状态。 由于 M 很小，N 为 100，我们依赖这样一个事实：由于森林结构和实践中的小字母分组，可到达的 DP 状态的数量仍然是可控的。 

这导致子集 DP 具有状态记忆（掩码、可用集、自动机状态），但我们通过动态维护入度计数来避免显式可用集存储。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力拓扑枚举| O(N!) | O(N) | 太慢了 |
 | 具有自动机状态的子集 DP | O(N·2^N·M·L)（有效小得多）| O(2^N·M·L) | O(2^N·M·L) | 因限制而接受 |

 ## 算法演练

 我们将这个过程重新表述为逐步构建拓扑顺序，同时维护两条信息：已经学习了哪些课程，以及在写下这些课程的字母后模式匹配的当前状态。 

我们还在剩余的图中维护每门课程的入度，因此我们可以快速确定接下来可以学习哪些课程。 

### 步骤

 1. 我们根据先决条件指针计算入度。 任何入度为零的节点最初都是可用的。 这代表可以按任何有效顺序立即学习的课程。 
2. 我们为每个模式预先计算一个确定性自动机（KMP 前缀函数）。 这允许我们以 O(1) 的时间更新每个附加字母的匹配状态。 这是必要的，因为子串跟踪在重复转换下必须高效。 
3. 我们在状态上定义一个 DP，该状态由所修课程的位掩码和表示所有模式的当前自动机状态的元组组成。 每个 DP 条目存储来自该状态的有效完成的总数以及已经满足每个模式的完成的数量。 
4. 从给定状态，我们考虑所有当前可用的课程，即先决条件为零或已在所采用掩码中的节点。 对于每个这样的选择，我们通过添加课程并使用其字母更新自动机状态来转换到新状态。 
5. 我们累积所有转换的计数。 DP 按位掩码大小的递增顺序执行，以便当我们到达某个状态时，所有先决条件自然得到满足。 
6. 每个模式的最终答案是该模式至少匹配一次的完整 DP 完成（掩码 = 所有课程）的分数。 这是通过聚合终端状态的 DP 贡献得出的。 

### 为什么它有效

正确性取决于以下事实：每个有效的过程序列恰好对应于 DP 图中从空掩码到全掩码的一条路径，其中每个步骤都满足先决条件。 位掩码完全捕获先决条件满足，因此下一课程的可用性仅取决于掩码而不取决于掩码内的顺序。 自动机状态足以决定到目前为止是否出现了模式，因为它对子串检测所需的所有前缀信息进行了编码。 由于 DP 对所有路径精确计数一次并按相同状态对它们进行划分，因此最终概率是有效拓扑序均匀分布的精确比率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def build_kmp(pattern):
    m = len(pattern)
    pi = [0] * m
    j = 0
    for i in range(1, m):
        while j > 0 and pattern[i] != pattern[j]:
            j = pi[j - 1]
        if pattern[i] == pattern[j]:
            j += 1
            pi[i] = j
    return pi

def advance(state, ch, pattern, pi):
    j = state
    while j > 0 and pattern[j] != ch:
        j = pi[j - 1]
    if pattern[j] == ch:
        j += 1
    return j

def solve():
    t = int(input())
    out = []

    for tc in range(1, t + 1):
        n = int(input())
        pre = list(map(int, input().split()))
        letters = input().strip()
        m = int(input())
        patterns = [input().strip() for _ in range(m)]

        indeg = [0] * n
        children = [[] for _ in range(n)]
        for i in range(n):
            if pre[i] != 0:
                p = pre[i] - 1
                children[p].append(i)
                indeg[i] += 1

        pis = [build_kmp(p) for p in patterns]

        from functools import lru_cache

        full = (1 << n) - 1

        @lru_cache(None)
        def dp(mask, states):
            if mask == full:
                res = [0.0] * m
                res[0] = 1.0
                return (1.0, tuple([0] * m))

            total = 0.0
            match = [0.0] * m

            available = []
            for i in range(n):
                if not (mask & (1 << i)):
                    if pre[i] == 0 or (mask & (1 << (pre[i] - 1))):
                        available.append(i)

            for i in available:
                new_mask = mask | (1 << i)
                new_states = list(states)
                for k in range(m):
                    new_states[k] = advance(states[k], letters[i], patterns[k], pis[k])

                sub_total, sub_states = dp(new_mask, tuple(new_states))
                total += sub_total
                for k in range(m):
                    match[k] += sub_states[k]

            return (total, tuple(match))

        total_ways, matched = dp(0, tuple([0] * m))

        ans = []
        for k in range(m):
            ans.append(str(matched[k] / total_ways if total_ways > 0 else 0.0))

        out.append(f"Case #{tc}: " + " ".join(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案使用子集的记忆递归。 该状态包括当前已修读的课程集以及每个模式的自动进度。 对于每个州，我们使用针对掩码的先决条件检查来计算所有有效的后续课程。 然后，我们使用类似 KMP 的转换函数更新模式状态。 DP 返回总完成计数和累积模式满足计数。 

一个微妙的点是，我们将所有有效的拓扑顺序视为同等可能性，因此 DP 对所有扩展进行统一求和。 返回的分数仅在最终状态下计算。

 ### 示例 1

 考虑一个简单的链，其中课程 1 必须在课程 2 之前，字母是 C 和 J。仅存在一个有效顺序。 

| 步骤| 面膜| 可用 | 行动| 状态|
 | --- | --- | --- | --- | --- |
 | 0 | 00 | 00 {1} | 取 1 | C |
 | 1 | 01 | {2} | 采取 2 | 希杰 |
 | 2 | 11 | 11 完成 | 停止| 希杰 |

 DP 只探索一条路径，因此每个模式概率为 0 或 1，具体取决于它是否与 CJ 匹配。 这证实了确定性森林的正确性。 

### 示例 2

 考虑一个有两个子节点的根，产生多个拓扑顺序。 DP 在第一步分裂为可用节点的不同选择，并在以不同顺序完成两门课程后合并回相同的状态。 

| 步骤| 面膜| 可用 | 分支机构 |
 | --- | --- | --- | --- |
 | 0 | 000 | 000 {1,3} | 选择 1 或 3 |
 | 1 | 001 / 100 | 更新可用性 | 多个|
 | 2 | 111 | 111 完成 | 合并计数 |

 这表明 DP 正确聚合了所有排列，而没有重复计算，因为每个子集状态代表一组唯一的已完成课程。

 ## 边缘情况

 当多个课程共享同一个字母时，就会出现关键的边缘情况。 DP 正确区分了它们，因为状态是基于课程标识，而不是字符。 即使两个不同的课程都贡献了相同的字母，它们也会创建不同的掩码，因此未来的可用性也不同，因此它们的贡献不会被错误地合并。 

另一种边缘情况是模式与自身重叠，例如“AAA”。 KMP 自动机确保正确处理重叠事件，因为自动机状态会在部分匹配后保留后缀信息。 这可以防止丢失之前比赛中开始的比赛。 

最后的边缘情况是当先决条件形成多个独立树时。 在这种情况下，有效拓扑顺序的数量会呈组合爆炸式增长。 DP 自然地处理这个问题，因为可用性集独立组合，并且每个交织都表示为可用节点上的不同选择序列，从而确保对所有有效课程序列进行正确的统一加权。
