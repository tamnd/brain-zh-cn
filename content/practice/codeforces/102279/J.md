 ## 解决方案
 ## 问题理解

 显示的值是十进制字符串 (X)。 该故障恰好影响了两个数字位置，这意味着可以通过交换 (X) 两个不同位置的数字来获得预期的数字。 在通过这种交换获得的所有数字中，我们需要严格小于 (X) 的最大数字。 如果没有交换产生更小的有效十进制数，则答案是`-1`。 

输入可以大到 (10^{100})，因此数字最多可以包含 101 位数字。 这排除了在整数类型有限的语言中将该值视为固定宽度机器整数的可能性，但这也意味着位数很少。 即使是对字符串执行几百万次操作的算法也很容易满足一秒的限制。 我们可以安全地对位置对使用直接枚举。 

粗心的实现可能会错误地处理三种边缘情况。 为了`100`，交换`1`任何一个零都会产生一个以零开头的数字，因此没有有效的较小正整数表示形式，答案是`-1`。 在检查前导数字之前比较字符串的解决方案可能会意外接受`010`或者`001`。 

为了`999`，每对包含相同的数字。 交换任何对都会使数字保持不变，因此不存在严格较小的候选者，答案是`-1`。 仅仅因为候选是由交换生成而接受候选的解决方案将错误地返回`999`。 

为了`354`，交换第一个和第三个数字给出`453`，它更大，同时交换第二个和第三个数字给出`345`，较小。 正确答案是`345`。 这捕获了选择第一个较小候选者而不是最大候选者的实现。 

## 方法

 直接的方法是尝试每一对数字位置。 对于每一对，复制原始字符串，交换这两个数字，如果结果以零开头，则拒绝结果，并将其与 (X) 进行比较。 如果它小于 (X)，则只要它大于迄今为止找到的最佳候选，就保留它。 

这种蛮力是正确的，因为精确更改两位数字位置的每个可能结果都对应于一对 (i<j)，并且算法会检查每个这样的对。 保留最大的有效候选者即可准确给出所需的答案。 

这种方法的成本在实际约束下还是很小的。 对于 (n) 个数字，有 (\binom n2) 种可能的交换，并且构造或比较候选可以采取 (O(n)) 个字符操作。 因此最坏情况的复杂度是 (O(n^3))。 在最大可能长度 (n=101) 下，仅进行 (\binom{101}{2}=5050) 次交换，大约提供 (5050\cdot101) 或大约 510,000 个字符操作。 

我们可以做一个小的观察，减少不必要的工作。 假设(i<j)。 如果(X[i]\le X[j])，交换它们不能使数字变小。 第一个改变的位置是(i)，其数字要么保持相等，要么变大。 仅当 (X[i]>X[j]) 时才有可能得到较小的结果。 我们可以跳过所有其他对。 

暴力方法之所以有效，是因为输入仅包含大约一百位数字。 观察到只有与 (X[i]>X[j]) 配对才能减少数量，这进一步减少了候选数量，但简单枚举被接受的主要原因是数字计数异常少。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(n^3)) | (O(n)) | (O(n)) | 已接受 |
 | 配对过滤 (X[i]>X[j]) | (O(n^3)) 最坏情况 | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1. 将 (X) 作为字符串读取，而不是将其转换为整数。 字符串表示形式直接提供对每个数字的访问，并且避免了对整数大小的任何依赖。 
2. 将最佳答案初始化为不存在。 我们仅在找到产生小于 (X) 的有效数字的交换后才创建答案。 
3. 枚举每对位置 (i<j)。 这些对代表受故障影响的两位数字的所有可能选择。 
4. 如果 (X[i]\le X[j])，则跳过该对。 交换后的数字与 (X) 不同的第一个位置是 (i)，新的数字将是 (X[j])。 由于 (X[j]\ge X[i])，结果不能严格小于。 
5. 复制 (X) 并交换位置 (i) 和 (j)。 我们复制而不是修改原始字符串，因为每个候选都必须从相同的原始数字生成。 
6. 如果候选人的第一个数字是，则拒绝该候选人`0`。 前导零将不再代表预期数字的有效十进制表示形式。 
7. 由于(X[i]>X[j])，候选已经保证小于(X)，因此将其与当前最佳候选进行比较。 当新的候选者更大时，更换最佳候选者。 
8. 检查完所有对后，打印最佳候选（如果存在）。 否则打印`-1`。 

### 为什么它有效

 考虑任何有效答案 (Y)。 由于通过交换恰好改变了两位数字，因此存在一对唯一的位置 (i<j)，其数字产生 (Y)。 对于 (Y<X)，第一个更改的位置 (i) 必须接收较小的数字，因此必然 (X[i]>X[j])。 该算法检查该对，构造 (Y)，并接受它，除非它具有无效的前导零。 因此，每个有效的候选人都会被考虑。 该算法保留所有接受的候选者中的最大值，因此最终结果正是通过一次交换可获得的小于（X）的最大数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    best = None

    for i in range(n):
        for j in range(i + 1, n):
            if s[i] <= s[j]:
                continue

            t = list(s)
            t[i], t[j] = t[j], t[i]

            if t[0] == '0':
                continue

            candidate = ''.join(t)

            if best is None or candidate > best:
                best = candidate

    print(best if best is not None else "-1")

if __name__ == "__main__":
    solve()
```输入存储在`s`作为字符串，因此可以直接访问每个数字，并且等长十进制字符串之间的比较与它们的数值之间的比较具有相同的顺序。 

嵌套循环生成每对 (i<j)。 条件`s[i] <= s[j]`是一个有用的修剪步骤。 当数字相等时，交换不会改变任何内容。 什么时候`s[i] < s[j]`，第一个变化的数字变大，因此结果数字大于（X）。 

候选者是从新列表创建的，因此交换不会影响以后的迭代。 这是排列式暴力破解中常见的错误来源：修改原始数组而不恢复它会使后面的候选数组依赖于之前的交换。 

前导零检查发生在接受候选者之前。 例如，交换`1`和`0`在`100`创造`001`，不得将其视为有效数字`1`。 

解决方案中的任何地方都没有整数转换。 Python 本身支持任意大小的整数，但将输入视为字符串可以使预期的表示形式明确，并使每个操作与位数成比例。

 ## 边缘情况

 对于`100`，算法检查`(0,1)`和`(0,2)`。 两种交换都会在数字上减少数量，但它们会创造`010`和`001`，因此前导零检查会拒绝两者。 这对`(1,2)`包含相同的数字并被跳过。 最佳答案仍然不存在，因此算法打印`-1`。 

为了`999`，每一对都有相同的数字。 每对都会被跳过`s[i] <= s[j]`条件，因为交换相同的数字不能产生更小的数字。 结果是`-1`，而不是不变的值`999`。 

为了`2`，只有一位数字，因此嵌套循环根本不包含数字对。 两个不同的数字不能互换，不会留下任何候选数字并产生`-1`。 

为了`354`，唯一有用的对是位置 1 和 2，使用从零开始的索引。 自从`5 > 4`，交换它们会产生`345`。 候选答案是有效的，比原来的小，成为最佳答案。 算法打印`345`。 

为了`11101`，交换`1`在位置 2 处`0`在位置 3 给出`11011`。 其他有用的交换要么产生更小的候选者，要么不会改进这个候选者。 算法保持`11011`，这是最大的有效结果。 

对于最大长度输入，算法永远不会将数字转换为机器整数。 每个操作都直接对其十进制字符进行操作，因此 101 位边界的处理方式与短输入完全相同。
