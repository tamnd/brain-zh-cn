 ## 解决方案
 ## 问题理解

 棋盘上有 (N+1) 个位置，排列成圆圈。 位置（0），对应于报表中的第一个位置，属于政府，永远不会导致付款。 其他（N）个位置是可以拥有的财产。 

共有三名选手，Seo、B21 和 Lowie。 每次玩家移动时，他们的位移都是固定的：Seo 总是移动 (V_s)，B21 总是移动 (V_b)，Lowie 总是移动 (V_l)。 他们按照这个顺序反复移动。 当玩家到达无主财产时，他们就会拿走它。 到达他们自己的财产不会执行任何操作，而到达另一个玩家的财产会立即创建我们正在寻找的事件。 

任务是找出第一次付款发生时发生的骰子数量。 如果在每个玩家允许的 (10^9) 步时间内没有发生支付，则所需的输出为 (3\cdot10^9)。 

这些界限使得直接模拟每个玩家的所有 (10^9) 回合是不可能的。 即使每轮的工作量非常小，也需要大约三十亿次迭代。 然而，电路板尺寸仅为 (N+1\le100001)，这强烈表明相关行为应在与 (N) 成比例的匝数之后重复。 

第一个微妙的案例是到达政府职位。 例如，与`3 1 1 1`，董事会有四个职位。 Seo 在第一次滚动时达到属性 1，B21 在第二次滚动时达到相同的属性，所以答案是`2`。 如果实施粗心，将起始头寸视为普通财产，则会错误地报告付款。 

另一种边界情况是运动等于 (N)。 为了`3 3 3 3`，棋盘大小为四，因此每个玩家每回合移动三个位置。 Seo 在第 1 卷上占据了位置 3，B21 在第 2 卷上到达了位置。答案是`2`。 使用模 (N) 而不是模 (N+1) 会默默地给出错误的电路板几何形状。 

动作的顺序也很重要。 为了`3 1 2 3`，Seo 在第 1 卷上声称位置 1，B21 在第 2 卷上声称位置 2，Lowie 在第 3 卷上声称位置 3。在 Seo 的第二步中，他到达了 B21 已经拥有的位置 2，所以答案是`4`。 在检查所有权之前处理整轮的模拟会忽略所有权在每次单独掷骰后立即更改的事实。 

最后，游戏可以永远重复，无需付费。 样品`29 6 10 15`就是这种情况，正确答案是`3000000000`。 仅仅因为每个玩家都重新访问了某些位置而停止是不够的，除非已经建立了整个游戏状态的重复。 

## 方法

 最简单的解决方案是完全模拟游戏发生的情况。 保存每个玩家的当前位置以及存储哪个玩家拥有每个属性的数组。 处理 Seo，然后处理 B21，然后处理 Lowie，用模 (N+1) 更新当前位置，并立即检查目的地。 如果为空，则指定其所有者。 如果它属于其他人，则返回当前的卷数。 

这个模拟是完全正确的，因为它完全遵循游戏描述的状态转换。 它的问题是停止条件。 该语句允许每个玩家移动 (10^9) 次，因此最坏的情况将需要 (3\cdot10^9) 次模拟掷骰，这远远超出了一秒的限制。 

关键的观察结果是棋盘恰好包含 (N+1) 个位置。 考虑一名玩家在进行了 (N+1) 次行动之后。 他们的总位移是

 [
 (N+1)V。 
]

 也就是说，玩家在尺寸为 (N+1) 的棋盘上绕了 (V) 圈，因此玩家正是在他们开始的地方。 更重要的是，由于移动量是固​​定的，因此接下来（N+1）次移动所达到的位置顺序与之前（N+1）次移动的顺序相同。 这是官方社论使用的中心周期性观察。 

每个玩家移动 (N+1) 步后，所有三名玩家都回到初始位置。 他们的移动顺序也回到了一轮开始时，并且在该块期间可以声明的所有财产在下一个块中都以完全相同的方式遇到。 如果在前 (3(N+1)) 轮中没有发生付款，则下一个区块将完全重复，因此以后永远不会发生付款。 

由于 (N\le100000), (3(N+1)\le300003)。 因此，我们可以用最多大约三十万步来代替可能需要三十亿步的模拟。

 ## 算法演练

 1.让`m = N + 1`，因为完整的圆形板包含政府立场加上 (N) 个属性。 使用索引存储每个位置`0`通过`m-1`， 在哪里`0`是政府的立场。 
2. 创建长度为所有权的数组`m`。 最初，每个条目都是零，意味着无主。 进入位置`0`从未被认领，因为它属于政府。 
3. 保持三个当前位置，最初全部为零。 还保留三个固定移动值（V_s，V_b，V_l）。 
4.最多模拟`m`完成回合。 在每一轮中，按照 Seo、B21、Lowie 的确切顺序处理三位玩家。 玩家使用模数通过固定移动值前进`m`。 
5. 每次移动后立即增加全局滚动计数器。 该计数器代表实际发生的骰子数量，因此如果当前目的地属于另一个玩家，则返回它会准确给出所请求的答案。 
6. 如果目的地为零，则忽略它，因为政府拥有该位置。 如果其所有者为零，则将当前玩家指定为其所有者。 如果其所有者已经是当前玩家，则不会发生任何事情。 如果其所有者是另一个玩家，则返回当前掷骰数，因为这是第一次付款。 
7.如果全部`3*m`可能的卷在不付款、退货的情况下进行处理`3000000000`。 这些之后的状态`m`每个玩家的移动与初始状态完全相同，因此每个未来的块都会重复相同的转换并且不能引入支付。 

### 为什么它有效

 不变的是，在每次模拟掷骰之前，存储的位置和所有权数组准确地描述了相同掷骰次数后的真实游戏。 每次运动都使用正确的固定位移和模数 (N+1)，所有权在到达目的地后立即更新。 因此，算法第一次看到另一个玩家的所有者正是真实游戏中的第一次付款。 

如果在每个玩家的 (N+1) 次移动过程中没有出现付款，则所有三个位置都将返回零，因为每个玩家已经移动了整数个完整的棋盘圈。 然后，相同的固定移动值和相同的转弯顺序会再现相同的目的地序列。 由于所有权状态也是由相同的序列产生的，没有冲突，所以未来的游戏会无限地重复。 因此返回`3000000000`是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, vs, vb, vl = map(int, input().split())

    m = n + 1
    moves = (vs, vb, vl)

    # owner[pos] = 0 if the property is unowned,
    # otherwise 1, 2, or 3 for the corresponding player.
    owner = [0] * m

    # All players start at the government position.
    pos = [0, 0, 0]

    rolls = 0

    # After m moves by each player, the whole game state repeats.
    for _ in range(m):
        for player in range(3):
            pos[player] = (pos[player] + moves[player]) % m
            rolls += 1

            p = pos[player]

            # Position 0 belongs to the government.
            if p == 0:
                continue

            if owner[p] == 0:
                owner[p] = player + 1
            elif owner[p] != player + 1:
                print(rolls)
                return

    print(3000000000)

if __name__ == "__main__":
    solve()
```第一部分将输入转换为电路板尺寸`n + 1`。 这是实现中最重要的索引选择。 政府仓位用零表示，而(N)个地产占据仓位`1`通过`n`。 

这`owner`数组存储每个属性的当前所有者。 没有必要为政府职位存储任何特殊的东西，因为`p == 0`check 在查询所有权数组之前会跳过它。 

外循环完全运行`m`次。 在每次迭代期间，每个玩家都会获得一个回合，因此模拟正好覆盖每个玩家的 (N+1) 回合，或者总共 (3(N+1)) 次掷骰。 

内循环使用`player`价值观`0`,`1`， 和`2`，对应 Seo、B21 和 Lowie。 数组中存储的所有者是`player + 1`，这让零仍然是无主财产的特殊价值。 

位置更新使用`(pos[player] + moves[player]) % m`。 模必须是`N+1`， 不是`N`，因为圆板上有 (N+1) 个位置。 

在检查目的地之前，滚动计数器会递增。 如果在该移动中发生付款，则请求的答案包括导致付款的掷骰，因此当前值`rolls`正是答案。 

Python整数具有任意精度，因此需要哨兵值`3000000000`不需要特殊的整数类型。 实际模拟最多执行`300003`滚动，因此时间和内存使用量都在限制范围内。

### 示例 2

 对于`29 6 10 15`，董事会有`30`职位。 每个玩家在 30 次移动后返回到零位置，因为他们的总位移是 30 的倍数。 

| 玩家| 运动 | 仓位达到模 30 |
 | --- | --- | --- |
 | 搜索引擎优化 | 6 | 6, 12, 18, 24, 0, ... |
 | B21 | 10 | 10 10, 20, 0, 10, 20, ... |
 | 洛伊| 15 | 15 15, 0, 15, 0, ... |

 这三个序列访问的非零位置是不相交的。 因此，没有一个玩家能够到达另一个玩家拥有的财产。 每个玩家移动 30 次后，所有三者都会归零，并且所有权模式会重复，因此后面的区块无法创建付款。 

因此该算法完成了所有`3 * 30 = 90`模拟卷和输出`3000000000`。 模拟不需要代表十亿个允许的回合，因为 30 步循环已经证明游戏将永远重复。

 ## 边缘情况

 对于`3 1 1 1`，棋盘尺寸为四。 Seo 从位置 0 移动到位置 1 并占据它。 然后B21从位置0移动到位置1并找到Seo的所有权，因此第二卷是第一笔付款。 算法返回`2`，同时正确地将零号位置视为政府位置。 

为了`3 3 3 3`，模基是四而不是三。 Seo 从零上升到第三位并占据了它。 B21 也移动到第三位并立即向 Seo 付款，产生`2`。 此案例捕获了错误使用的实现`n`作为圆板的长度。 

为了`3 1 2 3`，前三轮产生三个不同的属性：Seo 拥有位置 1，B21 拥有位置 2，Lowie 拥有位置 3。Seo 的第二步到达位置 2，因此付款发生在卷 4 上。所有权数组在每次移动后都会更新，这保留了游戏所需的确切时间顺序。 

为了`29 6 10 15`，所有三个玩家都只重复访问其他人没有访问过的位置。 每个玩家移动 30 次后，所有位置和所有权转移再次进入相同的循环。 该算法检测到这些中没有付款`90`滚动和返回`3000000000`，而不是尝试模拟每个玩家剩余的十亿回合。
