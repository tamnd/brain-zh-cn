 ## 解决方案
 ## 问题理解

 折线描述一维地形轮廓。 由于x坐标是严格递增的，每一对连续的点形成一个地形段，当地形两侧升高到足以阻止水逸出时，雨水只能停留在凹陷处。 

对于任何凹陷，水面都是水平的。 假设其左边界为点(i)，右边界为点(r)。 水位是两个边界高度中较低的一个，

 [
 h=\min(y_i,y_r)。 
]

 水域是地形和水平线 (y=h) 之间的区域，但仅限于地形低于该线的区域。 任务是找到所有这些被困区域的总和，其中每一块地形最多属于一个计算区域。 

约束 (n\le 10^5) 排除检查每对点。 在最坏的情况下，二次算法将执行大约 (10^{10}/2) 对检查，远远超出 2 秒限制。 坐标最多为 (10^6)，因此整条折线的总水平宽度最多为 (10^6)，但这并不能使从每个起点进行扫描都可行。 我们需要一个 (O(n)) 或 (O(n\log n)) 的解决方案。 

有几种边缘情况很容易被错误处理。 只有两点，根本没有封闭的凹陷。 例如，```
2
0 0
1000000 1000000
```有答案`0`。 假设每对都定义一个盆地的解决方案会错误地在这里产生水。 

相同的高度也很重要。 为了```
3
0 2
1 0
2 2
```答案是`1`，因为两侧形成一个水位为 2 的三角形盆地。当最大高度等于左侧高度时，仅使用严格更大点的粗心次更大实现可能无法识别右侧边界。 

右边界也可以低于左边界。 为了```
3
0 3
1 0
2 2
```水位是 2，而不是 3，因为水在高度 2 处溢出右侧。答案是`2`。 这就是为什么边界高度必须是`min(y_i, y_r)`。 

最后，当右端点高于水面时，最后一个地形段在其内部某处穿过水面。 为了```
4
0 2
1 0
2 1
3 3
```水位为 2。前两个段贡献 (1) 和 (1.5)，而最后一段仅贡献 (0.25)，因为只有高度 2 以下的部分含有水。 答案是`2.75`。 将整个最后一段视为淹没会多算。 

## 方法

 直接的方法是尝试每个可能的左边界（i），找到每个可能的右边界（j>i），并计算该对可以保留多少水。 有 (n(n-1)/2) 对，对于 (n=10^5) 来说大约有 (5\cdot10^9) 对。 即使每对都在恒定时间内处理，这也已经太慢了。 如果面积也通过扫描区间来计算，复杂度就会变成三次方。 

有用的观察是我们不需要考虑任意的​​右边界。 从点 (i) 开始，唯一有意义的右边界是右侧第一个高度严格大于 (y_i) 的点。 如果存在这样的点，则它之前的每个点最多为 (y_i)，因此从 (i) 开始的水在溢出之前恰好到达该边界。 如果不存在更大的点，水最终会从最高点溢出到右侧。 我们选择该后缀最大值的第一次出现作为边界。 

这正是官方社论描述的结构：对于每个（i），找到（y_{r_i}>y_i）中最小的（r_i>i），或者，如果不存在，则在右侧位置中第一个达到最大高度的位置。 生成的范围要么是嵌套的，要么是完全分离的，这允许通过直接从一个范围跳转到下一个范围来处理它们。 

每个点的第一个较大位置可以通过 (O(n)) 中的单调堆栈找到。 后备后缀最大值可以通过一次从右到左的扫描来计算，也是在 (O(n)) 中。 

一旦知道边界 (r_i)，我们就可以通过遍历从 (i) 到 (r_i) 的线段来计算水域面积。 实际处理的范围是不相交的，因为在处理 ([i,r_i]) 后，我们从 (r_i+1) 继续。 因此，虽然单个范围可能包含许多段，但整个算法处理的段总数仅为 (O(n))。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(n^2)) 或更糟 | (O(n)) | (O(n)) | 太慢了 |
 | 最佳 | (O(n)) | (O(n)) | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1.将折线读入数组`x`和`y`。 严格增加`x`意味着每个地形段都可以独立集成。 
2. 计算`next_greater[i]`，右侧的第一个索引`i`和`y[index] > y[i]`。 从右到左处理索引，同时维护高度严格递减的堆栈。 在查询堆栈之前`i`，删除每个高度最大为`y[i]`，因为这些点都不能成为第一个严格更高的点`i`。 
3. 计算`suffix_idx[i]`，严格位于右侧的索引中达到最大高度的第一个位置`i`。 从右向左扫描时，保持迄今为止看到的最佳点。 当当前高度严格大于该点时，替换该点。 当高度相等时，保留现有点，因为它距离右侧较远，并且当前点不属于所考虑的后缀的一部分`suffix_idx[i]`。 
4. 开始于`i=0`。 如果`next_greater[i]`存在，将其用作`r`。 否则使用`suffix_idx[i]`。 如果右边没有点，则没有可能的盆地，算法停止。 
5. 将水位设置为`h=min(y[i],y[r])`。 该范围内的每个内部顶点最多`h`，根据定义`r`。 如果`y[r] > h`，只有最后一段可以穿过水面。 如果`y[r] <= h`，每一段都完全在水面以下或之上。 
6. 对于从 ((x_1,y_1)) 到 ((x_2,y_2)) 的完全淹没路段，地形是线性的，因此其平均高度为 ((y_1+y_2)/2)。 有水位`h`，其贡献为

 [
 (x_2-x_1)\left(h-\frac{y_1+y_2}{2}\right)。 
]

 为了避免重复减半，该实现存储了两倍的区域：

 [
 (x_2-x_1)(2h-y_1-y_2)。 
]

 1. 如果最后一段从 (y_1\le h) 到 (y_2>h)，则水仅占据线条到达高度之前的部分`h`。 深度是一个高度为 (h-y_1) 的三角形。 交叉距离为

 [
 (x_2-x_1)\frac{h-y_1}{y_2-y_1},
 ]

 所以面积是两倍

 [
 (x_2-x_1)\frac{(h-y_1)^2}{y_2-y_1}。 
]

 该实现使用以下方法评估此合理值`Decimal`即使对于大坐标也能保持足够的精度。 

1.将当前范围的面积添加到答案中并设置`i=r+1`。 范围在计算的部分中不能重叠，因此每个地形段最多处理一次。 

### 为什么它有效

 对于每个起点 (i)，所选的 (r_i) 正是源自 (i) 的水可以逸出的第一个位置。 如果存在更高的点，则该点之前的所有点都不高于 (y_i)，因此下边界高度为 (y_i)。 如果不存在更高的点，则后缀上的最高点是第一个可以溢出水的地方，其高度决定了水位。 因此 ([i,r_i]) 描述了一种最大的滞水结构。 

两个这样的结构要么是嵌套的，要么是不相交的。 当我们处理最左边的结构然后跳转到`r_i+1`，任何嵌套结构都已包含在已处理区域中，而任何不相交结构稍后开始。 因此，跳跃永远不会跳过属于单独流域的水，并且永远不会对同一段进行两次计数。 由于每个处理段准确地贡献了其几何水域面积，因此累加的结果就是所需的总面积。 

## Python 解决方案```python
import sys
from decimal import Decimal, getcontext

input = sys.stdin.readline

getcontext().prec = 40

def solve(data=None):
    if data is None:
        tokens = iter(sys.stdin.buffer.read().split())
    else:
        tokens = iter(data.split())

    n = int(next(tokens))
    x = [0] * n
    y = [0] * n

    for i in range(n):
        x[i] = int(next(tokens))
        y[i] = int(next(tokens))

    if n <= 2:
        return "0.0000000000\n"

    # next_greater[i] = first j > i with y[j] > y[i].
    next_greater = [-1] * n
    stack = []

    for i in range(n - 1, -1, -1):
        while stack and y[stack[-1]] <= y[i]:
            stack.pop()

        if stack:
            next_greater[i] = stack[-1]

        stack.append(i)

    # suffix_idx[i] = first position attaining the maximum y
    # among positions strictly to the right of i.
    suffix_idx = [-1] * n
    best = -1

    for i in range(n - 1, -1, -1):
        suffix_idx[i] = best

        if best == -1 or y[i] > y[best]:
            best = i

    # Store twice the integer/rational area.
    integer_area2 = 0
    fractional_area2 = Decimal(0)

    i = 0

    while i < n - 1:
        r = next_greater[i]

        if r == -1:
            r = suffix_idx[i]

        if r == -1:
            break

        h = min(y[i], y[r])

        k = i
        while k < r:
            x1, y1 = x[k], y[k]
            x2, y2 = x[k + 1], y[k + 1]
            dx = x2 - x1

            if y2 <= h:
                # Entire segment is below the water surface.
                integer_area2 += dx * (2 * h - y1 - y2)
            else:
                # The segment crosses the water surface.
                # Only the triangular part before the crossing is wet.
                dy = y2 - y1
                numerator = dx * (h - y1) * (h - y1)

                fractional_area2 += (
                    Decimal(numerator) / Decimal(dy)
                )

                # This must be the last segment of this range.
                break

            k += 1

        i = r + 1

    area = (
        Decimal(integer_area2) + fractional_area2
    ) / Decimal(2)

    return f"{area:.10f}\n"

def main():
    sys.stdout.write(solve())

if __name__ == "__main__":
    main()
```第一次扫描用递减的单调堆栈构造下一个更大的数组。 加工点时`i`，每个不高于的堆栈元素`y[i]`作为第一个严格更高的点永久无用，因此删除它是安全的。 

后缀扫描处理不存在严格更高点的情况。 分配给`suffix_idx[i]`在考虑点之前发生`i`，这就是使存储索引严格引用右侧的原因。 等高故意不替换`best`，因为较早的点是该后缀最大值第一次出现。 

主循环使用`r`作为这两个结构选择的边界。 如果`r=i+1`，没有内部地形部分，贡献为零。 跳转到`r+1`仍然是正确的，因为该范围不能包含任何正面积盆地。 

面积以双倍形式累积。 完整的线段贡献整数，而最终的交叉线段可以产生有理数。 Python 整数具有任意精度，并且`Decimal`处理有理数部分，而不会损失二进制浮点值可能为大坐标引入的精度。 

穿越案值得特别关注。 什么时候`y2 > h`，使用普通的梯形公式可以计算出水面以上的线段部分。 相反，只有三角形`y1`到高度`h`被淹没。 自从`r`就是上面的第一点`y_i`当存在这样的点时，在处理的范围内最多可以有一个这样的交叉线段。

|`i`|`r`|`h`| 部门贡献| 累计面积|
 | ---| ---| ---| ---| ---|
 | 1 | 4 | 1 | (0.5+0.5+0) | (1) |

 第一个范围是`[1,4]`，因此算法跳转到点 5。点 5 和点 6 相邻，因此该范围不包含内部凹陷。 它的两个边界高度是 2 和 3，没有给出正面积的捕获区域。 

从第 4 点开始的范围也解释了小数项。 它的左侧从高度5上升到2，与点6配对时水位为3。`(5,5)`到`(7,2)`在到达点 5 的端点之前穿过高度 3，产生 (1/3) 的三角形贡献。 该段来自`(7,2)`到`(8,3)`贡献另一个（1/2）。 最终结果是

 [
 1+\frac13+\frac12=\frac{11}{6}=1.8333333333\ldots
 ]

 与示例输出匹配。

 ## 边缘情况

 由于只有两个点，该算法不计算任何范围，因为没有内部段。 为了```
2
0 0
1000000 1000000
```

`i=0`没有能够创建封闭区域的有意义的右边界，因此结果正是`0`。 

对于相同的高度，请考虑```
3
0 2
1 0
2 2
```第一个点的右侧不存在严格意义上的更大点。 后缀最大值是高度 2 处的第三个点，因此`r=2`和`h=2`。 两个单位宽度的段中的每一个都形成一个面积为 (1/2) 的三角形，总共为`1`。 回退规则处理相等性，而不将相等端点视为严格更大的点。 

当右边界低于左边界时，```
3
0 3
1 0
2 2
```后缀最大值为高度 2。该算法使用`h=min(3,2)=2`，而不是 3。每个线段贡献一个面积为 1 的三角形，给出`2`。 这与物理行为相符，因为水一旦达到高度 2 就会溢出右侧边界。 

对于交叉线段，```
4
0 2
1 0
2 1
3 3
```右边界为最后一个点，水位为2。第一段贡献1，第二段贡献（1.5），高度1到高度3的最后一段在中途穿过水面。 它的湿部分是一个三角形，底边为 (1/2)，高度为 1，贡献为 (1/4)。 总计为（1+1.5+0.25=2.75）。 该实现的特殊交叉公式准确地捕获了该部分段。 

最后一个微妙的情况是紧邻起点的边界。 如果`r=i+1`，两个边界点之间没有内部地形，因此该范围不能包含正面积的水。 该算法加零并跳转到`r+1`，防止相差一错误和不必要的处理。
