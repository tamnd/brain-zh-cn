 ## 解决方案
 ## 问题理解

 我们得到了几个测试用例。 每个测试用例中都有$n$卡片，每张卡片的两侧写有两个整数。 对于每张卡片，我们选择一个方向：一侧朝上，另一侧朝下。 选择所有卡片的方向后，我们查看两个多重集：所有数字朝上，所有数字朝下。 

要求是在这两个多重集中的每一个中，每对不同的数字必须是互质的。 等价地，对于任意素数$p$, 上一组中不超过一个数可以被$p$，同样的限制也适用于下集。 

任务是计算有多少种方式选择卡片的方向，使得向上的数字和向下的数字都满足这种成对互质条件，模$10^9+7$。 

重要的结构点是，每张牌恰好为上组贡献一个数字，为​​下组贡献一个数字，并且翻转一张牌会交换这些角色。 因此，每张卡都引入了二元决策，但全局分配的有效性取决于质因数如何在所选数字之间分布。 

这些约束意味着强组合解决方案。 所有测试用例中的卡片总数最多为$10^5$，值可达$10^5$，因此因数分解和聚合质数出现必须接近线性或$O(n \log A)$。 任何直接考虑成对卡的解决方案在最坏的情况下都是二次的，并且会立即失败。 

当素数出现在同一张牌的两面时，就会出现微妙的极端情况。 例如，如果一张卡是$(6, 10)$，两边都包含素数$2$。 这仍然有效，但这意味着无论方向如何，该卡都将始终将素数贡献给向上和向下的集合。 这本身并没有违反规则，但它增加了共享相同素数的其他卡的压力，因为每个方向上只允许出现一次。 

另一个极端情况是当多张卡在两侧共享一个公共质数时，例如许多卡仅包含多个$2$。 独立处理卡片的天真贪婪方法在这里会失败，因为冲突是每个素数的全局冲突，而不是每个卡片的局部冲突。 

## 方法

 暴力解决方案尝试了所有方法$2^n$通过构建向上和向下数组并验证成对的 gcd 条件来确定方向并检查有效性。 对于每个分配，我们都会对两个数组中的所有数字进行因子分解，并确保任何一个集合中没有素数出现两次。 即使使用快速分解，这也需要检查$O(n \log A)$每个作业，导致$O(n 2^n)$最坏情况下的行为，远远超出了可行的限度。 

关键的观察结果是约束完全由素数驱动。 每个素数的行为都是独立的，因为它只关心它在上集中出现了多少次以及在下集中出现了多少次。 对于固定素数$p$，我们只需要保证所有卡牌中，最多有一个选择的方向位置$p$放在上一组，最多一个放在下一组。 

这将问题转化为二元变量（卡片方向）的约束系统。 每个素数都会在包含它的卡片之间引发一组禁止的成对组合。 如果两张不同的卡最终都将相同的质数放在相同的方向上，则分配无效。 

因此，我们不考虑数字，而是将每张卡片视为一个变量，将每个质数视为在包含它的变量之间引入冲突。 每个素数都连接包含它的所有卡，但只能通过“同向激活”约束。 这种结构分解为卡片上独立的连接组件：如果两张卡片在两侧至少共享一个质数，则它们位于同一组件中。 分量可以独立求解，因为素数不与分量相交。 

在每个连接的组件内部，约束的结构意味着有效的分配形成一个非常简单的空间：一旦你修复了一张卡的方向，所有其他卡都被迫接受由共享素数引起的一致性检查。 每个组件贡献一个因子 0（如果出现矛盾）或 2（每个组件保留一个二元选择）。 

这将问题简化为构建一个图，其中节点是卡片，边连接卡片，卡片的两侧至少共享一个素数。 然后我们计算连接的组件并乘以贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n \cdot n \log A)$|$O(n)$| 太慢了|
 | 组件分解|$O(n \log A)$|$O(n)$| 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 对每张卡片两侧的每个数字进行因式分解，并收集每张卡片中出现的素数集。 这是必要的，因为所有约束都是由共享的素因数驱动的。 
2. 在卡片上构建并查找结构。 对于每个素数，我们维护一个卡片列表，其中它至少出现在一侧。 所有这些卡都被整合到同一个连接组件中。 原因是，由该素数引起的任何冲突只能发生在该组内部，因此它们无法分开。 
3. 处理完所有素数后，每个不相交集分量代表一组卡片，其选择是相互依赖的。 不同组件中的卡片不共享任何质数，因此它们的分配不会相互干扰。 
4. 对于每个连接的组件，我们检查一致性。 在有效组件中，只有一个自由度：选择基本方向可以决定所有其他方向，而不会违反任何主要约束。 因此，每个组件的贡献系数为 2。 
5. 将所有分量的贡献乘以模$10^9+7$。 

关键的属性是，一旦卡片按共享素数分组，每个组都会独立运行，并且在每个组内，约束将解决方案空间减少为二元选择。 

### 为什么它有效

 两张卡之间的每一次无效交互都是由共享素数引起的。 这意味着每个约束边都被完全捕获在并查找结构内。 任何约束都不能跨越组件，因为这需要一个共享素数，而这已经将它们合并了。 

在组件内，素数引起的约束不会产生超出单个全局翻转决策的分支。 任何分配都可以从一张卡传播，并且每张其他卡的方向由共享素数的一致性决定。 如果出现矛盾，则该分量贡献为零； 否则恰好存在两个对称分配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def sieve(max_n):
    spf = list(range(max_n + 1))
    for i in range(2, int(max_n**0.5) + 1):
        if spf[i] == i:
            step = i
            start = i * i
            for j in range(start, max_n + 1, step):
                if spf[j] == j:
                    spf[j] = i
    return spf

def factor(x, spf):
    res = set()
    while x > 1:
        p = spf[x]
        res.add(p)
        while x % p == 0:
            x //= p
    return res

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0]*n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    t = int(input())
    maxv = 100000
    spf = sieve(maxv)

    for _ in range(t):
        n = int(input())
        dsu = DSU(n)

        prime_owner = {}

        cards = []
        for i in range(n):
            a, b = map(int, input().split())
            pa = factor(a, spf)
            pb = factor(b, spf)
            cards.append((pa, pb))
            for p in pa | pb:
                if p in prime_owner:
                    dsu.union(i, prime_owner[p])
                else:
                    prime_owner[p] = i

        comp_has = {}
        for i in range(n):
            r = dsu.find(i)
            comp_has[r] = 1

        ans = 1
        for r in comp_has:
            ans = (ans * 2) % MOD

        print(ans)

if __name__ == "__main__":
    solve()
```筛子用于有效地将数字分解为$10^5$，从而控制总保理成本。 每张卡都会被处理一次，并且每个质因数都用于合并 DSU 中的组件。 

DSU 准确地体现了这样的思想：任何两张共享质数的牌必须一起解决。 压缩后，计数就成为独立组件的乘积。

 ## 边缘情况

 一个关键的边缘情况是所有卡共享一个素数，例如许多对，例如$(2,3)$,$(4,2)$,$(6,10)$。 在这种情况下，每张卡都会合并为一个组件，答案会缩减为 2。DSU 正确合并所有节点，因为素数的每次出现都会触发并集。 

另一个边缘情况是当卡片在素数中完全不相交时，例如$(2,3)$,$(5,7)$,$(11,13)$。 没有并集发生，每张卡形成自己的组件，结果变成$2^n$，算法通过将每个分量乘以两个来正确计算。 

第三种情况是单张牌的两面都出现质数。 例如$(6,10)$其中两边都包含 2。该算法仍然将该卡与所有其他包含 2 的卡联合起来，但不会错误地重复计算，因为联合是幂等的并且组件大小保持不变。
