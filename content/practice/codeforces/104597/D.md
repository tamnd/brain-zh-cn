 ## 解决方案
 ## 问题理解

 我们正在与隐藏的价值互动$x$之间$1$和$n$。 了解的唯一途径$x$是将其与排列中存储的值进行比较。 

最初，排列是恒等式，所以位置$i$包含价值$i$。 当我们查询索引时$i$，我们按顺序做两件事。 首先，我们比较当前存储在位置的值$i$和$x$，并且我们被告知它是更小、相等还是更大。 其次，通过反转之间的段来修改排列$i$和当前位置$x$。 第二步使问题变得不标准：每个查询都会改变我们用来定位值的结构。 

目标是确定实际数值$x$，而不是它的位置，每个测试用例最多使用 50 个查询。 

约束条件$n \le 30000$排除任何在每个查询重建或扫描排列上花费线性工作的方法。 然而，50 个查询足够小，如果我们能够有效地支持每个比较，则对值空间进行对数搜索是合理的。 

主要的微妙之处在于，查询不仅提供信息，还以确定性但依赖于历史的方式移动元素。 忽略这一点并假设排列保持简单的幼稚策略很快就会崩溃，因为在几次查询之后，结构会变得严重混乱，除非精确跟踪。 

第一个查询是一个小但重要的边缘情况。 在发生任何逆转之前，排列是干净的，因此第一个比较是在$x$和文字索引值。 之后，所有值可能都发生了变化，因此任何假设“位置”的推理$i$包含价值$i$” 立即变得无效，除非我们明确维护排列状态。

 ## 方法

 暴力策略会尝试恢复$x$通过反复探索指标并仅通过比较进行推理，而不维护结构。 问题是，每次查询后，涉及当前位置的段上的排列都会颠倒。$x$，这意味着在固定索引处看到的值并不稳定。 在许多查询中，相同的索引可能表示完全不同的值，从而无法一致地解释比较。 即使尝试模拟所有可能性也会失败，因为每个查询都会引入呈指数增长的状态分支结构。 

关键的观察结果是，虽然排列发生了变化，但它以完全确定性的方式变化。 我们总是确切地知道应用了什么反转操作，因为我们控制查询索引并且我们知道在哪里$x$目前正在排列中。 这意味着我们可以显式地维护整个排列，包括从值到位置的逆映射。 

一旦接受这一点，每个查询就变得简单：我们可以要求比较$x$和任何已知值，通过查询该值当前所在的位置。 这将问题简化为值域上的标准搜索$[1, n]$，其中每个步骤都是一个比较预言。 

这使得可以对值进行二分搜索。 尽管排列不断变化，我们总是可以在其当前位置找到任何值，对其进行查询，并一致地更新结构。

 ## 算法演练

 我们在整个过程中维护两个数组：一个用于排列，另一个用于从值到位置的逆映射。 我们还跟踪当前位置$x$，它始终成为最近查询的索引。 

### 步骤

 1. 将排列初始化为恒等并构建逆映射，使得每个值$v$处于位置$v$。 我们还设置了当前位置$x$未知。 
2. 我们在第一个选择的索引处执行查询，通常是范围中间的位置或简单地 1。这给出了之间的直接比较$x$和已知值。 在这个查询之后，我们了解了当前的位置$x$，因为反转移动$x$到查询的索引。 
3. 从这一点开始，我们总是知道完整的排列。 当我们想要比较时$x$有一个值$v$，我们查询索引 where$v$目前位于。 
4. 我们对值范围进行二分查找$[1, n]$。 对于中点$mid$，我们使用逆映射定位它的当前位置并查询它。 响应表明是否$mid < x$,$mid = x$， 或者$mid > x$，它直接决定我们如何移动二分搜索边界。 
5. 每次查询后，我们对查询索引和当前位置之间的段应用所需的反转$x$。 这会更新排列和逆映射。 
6. 当查询返回相等时，我们立即输出找到的值。 

这样做的关键原因是每次比较总是与查询位置中存储的真实值进行比较，并且我们准确地了解每个值当前所在的位置。 排列会改变，但永远不会变得未知。 

### 为什么它有效

 在任何时刻，我们都保持排列状态的正确表示。 逆映射确保对于我们想要测试的任何值，我们都可以在恒定时间内找到它的当前位置。 每个查询都给出了真实的比较$x$和一个已知值，并且随后的反转是完全模拟的，因此不保留任何隐藏状态。 这保证了二分搜索决策始终基于准确的比较，这意味着搜索间隔始终正确缩小，直到$x$被识别。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(i):
    print("?", i)
    sys.stdout.flush()
    return input().strip()

def solve_case(n):
    # permutation and inverse map
    p = list(range(n + 1))
    pos = list(range(n + 1))

    def reverse(l, r):
        while l < r:
            vl, vr = p[l], p[r]
            p[l], p[r] = vr, vl
            pos[vl], pos[vr] = r, l
            l += 1
            r -= 1

    # initial query to discover x position movement behavior
    first = 1
    resp = ask(first)
    if resp == "=":
        print("!", 1)
        sys.stdout.flush()
        input()
        return

    # after first query, x is at position first
    x_pos = first

    # binary search over values
    lo, hi = 1, n

    while lo <= hi:
        mid = (lo + hi) // 2
        i = pos[mid]

        resp = ask(i)

        if resp == "=":
            print("!", mid)
            sys.stdout.flush()
            input()
            return

        # current position of x is always last queried index
        j = x_pos

        if i != j:
            reverse(min(i, j), max(i, j))
            x_pos = i

        if resp == "<":
            lo = mid + 1
        else:
            hi = mid - 1

    print("!", lo)
    sys.stdout.flush()
    input()

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        solve_case(n)

if __name__ == "__main__":
    main()
```该实现显式模拟排列，以便每个值的位置始终已知。 这`pos`数组至关重要，因为它让我们将“与中间值比较”转换为具体的索引查询。 

变量`x_pos`跟踪隐藏值当前所在的位置。 每次查询后都会更新它，因为该问题保证反转总是移动查询到的索引和之前的位置$x$到该段的另一端。 

两者都需要小心维护`p`和`pos`在反转过程中保持一致，否则后面的查询将引用错误的位置，并且二分搜索将中断。 

## 工作示例

 考虑一个小例子，其中$n = 5$和$x = 3$。 最初的排列是$[1,2,3,4,5]$。 

查询索引2后，我们比较$2$和$3$，得到“<”，并反转段$[2,3]$，生产$[1,3,2,4,5]$。 值 3 移动到位置 2，该位置成为$x$。 

现在假设我们通过位置 4 来查询值 4。我们比较$4$和$x=3$，得到“>”，并反转段$[2,4]$，生产$[1,4,2,3,5]$。 的位置$x$再次移动到查询索引。 

这个序列表明，尽管排列在变化，但我们总是确切地知道每个值的位置，因此比较仍然有意义。 

第二个例子$n = 4, x = 1$显示查询索引 1 时立即出现的相等情况。无论先前的结构如何，响应“=”都会终止该过程，这表明相等查询始终是稳定的锚点。

 ## 边缘情况

 对于$n = 2$，二分查找退化为单一比较。 排列反转仍然会发生，但逆映射确保比较仍然有效，因为我们总是查询值的正确当前位置。 

为了$x = 1$或者$x = n$，所有比较都会立即将搜索偏向一侧。 排列仍然会发生逆转，但由于我们明确地跟踪位置，因此我们永远不会丢失边界值的位置。 

对于第一个查询发生在端点的情况，整个系统仍然表现一致，因为反转要么影响完整前缀，要么不执行任何操作，并且保留每次操作后完全知道排列的不变性。
