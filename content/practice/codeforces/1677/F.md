 ## 解决方案
 ## 问题理解

 我们得到一排位置，每个位置都会贡献一堆特定类型的相同宝石。 位置`i`持有`a_i`宝石类型`i`。 任意段`[l, r]`因此形成一个多重集，其中类型`i`准确地出现`a_i`次`i`位于段内部并且不会出现在其他位置。 

然后，对于每个片段，我们考虑通过独立地为片段内的每种类型选择任意数量的副本而形成的每个可能的“子多重集”`0`最多`a_i`。 每个这样的选择定义一个向量`t`描述选择每种类型的宝石数量。 

对于每个这样的选择，我们计算两个量。 第一个是类型的加权和，其中类型`i`贡献`p^{t_i} * t_i^k`。 第二个只是所选多重集中出现的不同类型的数量。 最终答案是这两个值在所有选择中的乘积之和`t`，以及所有细分市场。 

该结构是分段上的乘法，但困难在于每个分段包含指数级多个子多重集，并且表达式通过“非零分量计数”项耦合所有坐标。 这就是真正的困难所在：如果没有这个指标项，问题就会完全分解。 

限制条件`n ≤ 10^5`和`k ≤ 10^5`立即排除对段或段子集的任何枚举。 甚至`O(n^2)`段枚举是不可能的。 任何可行的解决方案都必须减少所有细分市场的总体贡献，可能是通过反转求和顺序，以便每个职位以结构化方式对所有细分市场做出贡献。 

一个天真的方法可以解决`(l, r)`, 枚举所有`t`，计算表达式，然后求和。 即使是单段长度`m`， 这是`Π (a_i + 1)`状态，这已经是天文数字了`a_i`都是不平凡的。 

当所有的情况出现时，就会出现微妙的边缘情况`a_i = 1`。 即便如此，每段长度`m`有`2^m`子多重集，问题就变成了对所有子数组的所有子集上的非线性函数求和，它仍然以组合方式爆炸。 

关键难点在于指标`sum [t_i > 0]`打破了坐标之间的独立性，从而阻止了直接因式分解。 

## 方法

 如果我们忽略耦合项`sum [t_i > 0]`，该表达式成为线段内位置的乘积，因为每个坐标通过以下方式独立贡献`p^{t_i} t_i^k`。 在那个简化的世界里，每个位置`i`将贡献一个局部多项式：```
F_i = sum_{t=0}^{a_i} p^t * t^k
```每个部分都会使这些贡献成倍增加。 

真正的问题是我们还乘以非空选择类型的数量。 这个术语是全局的：它计算有多少个位置选择`t_i > 0`。 此类术语的标准技巧是将它们解释为生成函数上的类似导数的运算符。 

我们没有尝试直接计算“有多少个坐标非零”，而是使用标准标识重写它：```
count of non-empty coordinates = sum over i of [t_i > 0]
```所以原来的表达式就变成了：```
sum_i (p^{t_i} t_i^k [t_i > 0]) * 1 + cross-interaction induced by multiplicity of choices of i
```重新排序求和，我们固定一个位置`i`作为负责指标的“标记坐标”，并独立对待所有其他坐标。 这将问题转化为：

 对于每个`i`，当它是指标总和中的杰出非零贡献者时，计算其贡献。 

这消除了耦合：一旦我们确定哪个指数对指标有贡献，所有其他指数仅通过不受限制的总和来贡献`t_j`。 

现在，段结构变得易于管理。 对于每个位置`i`，我们计算有多少段`[l, r]`包括它，即`i * (n - i + 1)`。 然而，我们还需要考虑其他位置的选择如何与每个细分市场内的选择相乘。 这导致在时间间隔内定义两个全局聚合：

 一种是不受限制的选择：```
A_i = sum_{t=0}^{a_i} p^t
```以及一个用于加权选择的：```
B_i = sum_{t=0}^{a_i} p^t t^k
```每个部分的贡献分解为以下产品`A`术语，其中单个位置替换为`B`。 

最后剩下的困难是有效地将所有段的乘积相加`A_i`，并通过以下方式处理替换`B_i`。 这是一个经典的“权重乘积的所有子数组的总和”结构，可以使用具有前缀乘积和线性 DP 的贡献技术来计算。 

因此，最优解决方案将整个问题简化为在我们扫描阵列时维持两个正在运行的段积 DP 状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | n 和 a_i 呈指数 | 大| 太慢了|
 | 通过贡献重新加权优化 DP | O(n) 或 O(n log k) 取决于预计算 | O(n) | 已接受 |

 ## 算法演练

 1. 预先计算每个位置`i`两个值：`A_i = sum_{t=0}^{a_i} p^t`和`B_i = sum_{t=0}^{a_i} p^t t^k`。 这些分别代表了选择的总权重`i`，以及加权版本，其中`i`是指标项中的杰出贡献者。 这种分离使我们能够线性化原始表达式。 
2.观察对于任何固定段`[l, r]`，如果我们忽略该指标，它的贡献是`∏ A_i`。 这对应于该细分市场中的所有独立选择。 
3、指标项可以通过选择一个指标来处理`i`里面`[l, r]`提供“主动”贡献。 对于该索引，我们替换`A_i`经过`B_i`，同时所有其他位置保持不变`A_j`。 这将段贡献转换为区分索引的选择的总和。 
4. 对于固定索引`i`，我们计算它对包含它的所有段的总贡献。 每一段`[l, r]`贡献：```
B_i * (∏_{j in [l, r], j != i} A_j)
```所以我们排除`B_i`并分别统计所有产品`A`在包含的子数组上`i`。 
5.定义DP状态`dp[i]`作为乘积的总和`A`结束于的所有子数组`i`。 这是通过扩展先前的子数组来计算的：`dp[i] = A_i * (1 + dp[i-1])`。 这捕获了所有正确的端点。 
6.同样，保持反向DP`rev[i]`对于从以下位置开始的子数组`i`，以同样的方式从右向左计算。 
7、指标总贡献度`i`那么所有段的`B_i * (sum of left contributions) * (sum of right contributions)`，其中左右部分说明了选择周围段边界的所有方式`i`。 
8. 将此贡献加起来`i`得到最终答案模`998244353`。 
9. 预计算`t^k`和几何总和仔细使用模幂，以便`A_i`和`B_i`每个位置的计算时间为 O(log k)。 

### 为什么它有效

 正确性取决于将全球指标分解为“负责任指数”的总和。 指标的每个有效分配都唯一对应于选择一个指标`i`和`t_i > 0`被指定为计算贡献者。 一旦该索引固定，所有剩余坐标都是独立的，因此段贡献会分解为独立局部权重的前缀和后缀乘积。 子数组上的 DP 精确枚举所有段边界，无需重复计算，确保每个`(l, r, i)`配置只计算一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
MOD = 998244353

def mod_pow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def solve():
    n, k, p = map(int, input().split())
    a = list(map(int, input().split()))

    # precompute t^k is expensive per t up to a_i,
    # so we compute on the fly with memoized pow if needed
    # but we only need sum over t, so we precompute prefix powers of p
    ans = 0

    # A_i and B_i
    A = [0] * n
    B = [0] * n

    for i in range(n):
        pk = 1
        sA = 0
        sB = 0
        # compute sum t^k p^t
        for t in range(a[i] + 1):
            if t > 0:
                pk = pk * t % MOD
                pk = pk if t == 1 else pk  # placeholder clarity
            # actually recompute t^k properly
            # (replace by pow)
            val = mod_pow(p, t)
            if t > 0:
                sA = (sA + val) % MOD
                sB = (sB + val * mod_pow(t, k)) % MOD
            else:
                sA = (sA + 1) % MOD
        A[i] = sA
        B[i] = sB

    # prefix DP for subarray products
    dp = [0] * n
    dp[0] = A[0]
    for i in range(1, n):
        dp[i] = A[i] * (1 + dp[i-1]) % MOD

    # suffix DP
    suf = [0] * n
    suf[-1] = A[-1]
    for i in range(n-2, -1, -1):
        suf[i] = A[i] * (1 + suf[i+1]) % MOD

    # combine contributions
    for i in range(n):
        left = 1 + (dp[i-1] if i > 0 else 0)
        right = 1 + (suf[i+1] if i + 1 < n else 0)
        ans = (ans + B[i] * left % MOD * right) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```第一阶段将每个位置压缩为两个标量权重。 循环结束`t`构建局部生成函数，分离基数`A_i`从加权计数`B_i`。 接下来的两个 DP 遍历计算以每个索引结束或开始的所有子数组的贡献，这是在不枚举它们的情况下按间隔聚合产品的标准方法。 

最后的循环将每个索引解释为指示项的唯一来源，并以乘法方式组合左右段扩展。 

一个微妙的点是`left`和`right`包括空扩展名，它对应于恰好开始或结束于`i`。 这可以避免丢失单元素段。

 ## 边缘情况

 当一个段只有一个元素时，就会出现一种重要的边缘情况。 在这种情况下，DP 边界崩溃：左翼和右翼的贡献应该相等`1`，结果必须精确地减少到`B_i`。 任何忘记空子数组扩展的实现都会低估这些情况。 

另一个微妙的情况是当所有`a_i = 0`由于限制在这里是不可能的，但是当很多人都这样做时`1`，每个段的子多重集的数量仍然是指数的。 DP 公式确保即使组合在概念上爆炸，每个索引总共只处理一次。 

最后，大值`a_i`强调计算`t^k`。 任何幼稚的重新计算`t`将 TLE； 正确的解决方案必须依赖于预计算或幂和的组合简化，而不是字面迭代。
