 ## 解决方案
 ## 问题理解

 给定一棵树，其节点编号为 1 到 N，以节点 1 为根。每个节点都带有不同的标签，这些标签形成从 1 到 N 的数字的排列。 

对于每个节点，我们查看其根子树内的节点并收集它们的标签。 任务是确定所收集的标签集是否形成长度等于子树大小的完美排列。 换句话说，如果一个子树有 k 个节点，我们检查它的标签是否恰好是按某种顺序从 1 到 k 的数字。 

输出是一系列答案，每个节点一个，指示该节点的子树是否满足此属性。 

高达 200,000 的约束 N 强制采用线性或近线性解。 任何独立地重复检查整个子树的方法都会多次重新计算相同的结构，并趋向二次行为，这远远超出了可接受的限度。 即使像对每个子树进行排序这样的操作，在最坏的情况下也意味着每个节点的总成本约为 O(N log N)，在链形树上退化为 O(N^2 log N)。 

一个微妙的边缘情况来自于标签是全球唯一的这一事实。 这消除了子树内部重复项的任何歧义，但它也隐藏了关键的困难：即使没有重复，如果子树的值不完全在 1 到 k 的范围内，子树仍然可能无法满足条件。 

例如，考虑一个大小为 3 的子树，其中包含值 {2, 3, 4}。 即使它的大小完美并且没有重复项，它也是无效的，因为它与所需的规范编号不匹配。 

另一种情况是大小为 3 的子树包含 {1, 2, 4}。 这也会失败，如果不仔细推理，天真的“仅检查最小值和最大值”方法可能会错误地通过它。 

## 方法

 一种直接的方法是为每个节点计算其子树中的完整值列表，对其进行排序，然后验证它是否与序列 1 到 k 匹配。 这是正确的，因为它明确地重建了正在测试的条件。 问题是成本。 每个子树提取的大小都是线性的，并且排序添加了对数因子，因此在所有节点上，在许多子树重叠的大型树中，这变得非常昂贵。 

关键的观察是我们实际上并不需要值的完整排序。 由于每个标签都是全局唯一的，因此每个子树已经包含 k 个不同的整数。 唯一重要的是这 k 个整数是否准确地填充从 1 到 k 的区间，没有间隙。 该条件可以仅使用两个聚合来验证：子树内的最小值和最大值。 

如果大小为 k 的子树具有最小值 1 和最大值 k，则所有值都必须位于 [1, k] 内，并且由于恰好有 k 个不同值，因此它们必须占据该范围内的每个整数。 这将问题从维护集合减少到维护简单的子树统计。 

因此，我们从重新计算显式集切换到计算每个节点的子树大小、最小值和最大值的单个 DFS。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（子树提取+排序） | O(N² log N) | O(N² log N) | O(N) | 太慢了|
 | 带有子树 min、max、size 的 DFS | O(N) | O(N) | 已接受 |

 ## 算法演练

 我们以节点 1 为树的根并执行后序遍历，以便子级在其父级之前得到处理。

1. 从节点 1 开始 DFS，将树视为远离根的方向。 这确保了每个子树以自下而上的方式被恰好处理一次。 
2. 对于每个节点u，将其子树大小初始化为1，并将其最小值和最大值设置为P[u]。 这表示仅包含 u 的平凡子树。 
3. 遍历u的每个子节点v，跳过父节点以避免在无向树中循环返回。 
4. 从 DFS(v) 返回后，通过添加大小、取子树最小值的最小值和子树最大值的最大值，将 v 中的信息合并到 u 中。 此步骤将不相交的子子树组合成 u 的完整子树。 
5. 一旦处理完所有子节点，u 的子树就完全由三个值表示：sz[u]、mn[u]、mx[u]。 
6. 检查 mn[u] 是否等于 1，mx[u] 是否等于 sz[u]。 如果两者都成立，则将u标记为有效，否则标记为无效。 

合并步骤的正确性依赖于这样一个事实：树中的子树分解是不相交的：每个节点恰好属于一个子子树，因此子树上的聚合可以保留精确的计数和值范围而不会重叠。 

### 为什么它有效

 每个子树通过三个不变量维护其值的完整摘要：其大小、最小标签和最大标签。 由于所有标签在全局范围内都是不同的，因此这些摘要对于正在检查的特定条件来说是无损的。 大小为 k 且其值完全位于 [1, k] 范围内的子树必须包含该区间中的每个整数，因为即使跳过一个数字也会强制使用更小的大小或与最大界限相矛盾的间隙。 

## Python 解决方案```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    n = int(input())
    p = [0] + list(map(int, input().split()))
    
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)
    
    sz = [0] * (n + 1)
    mn = [10**18] * (n + 1)
    mx = [0] * (n + 1)
    ans = [False] * (n + 1)
    
    def dfs(u, parent):
        sz[u] = 1
        mn[u] = p[u]
        mx[u] = p[u]
        
        for v in g[u]:
            if v == parent:
                continue
            dfs(v, u)
            sz[u] += sz[v]
            mn[u] = min(mn[u], mn[v])
            mx[u] = max(mx[u], mx[v])
        
        if mn[u] == 1 and mx[u] == sz[u]:
            ans[u] = True
    
    dfs(1, -1)
    
    out = []
    for i in range(1, n + 1):
        out.append("YES" if ans[i] else "NO")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```DFS 在单次遍历中计算子树统计数据。 每个节点初始化自己的贡献，然后吸收其子节点的结果。 Parent 参数可防止重新访问无向邻接列表中的前一个节点。 

一个常见的实现陷阱是在合并子节点之前忘记初始化每个节点的 mn[u] 和 mx[u]，这会导致先前测试用例或递归调用的值泄漏到不相关的计算中。 另一个微妙的点是递归深度，因为 N = 200,000 的链形树将溢出默认的 Python 限制，而无需显式增加。

 ## 边缘情况

 单节点树是最简单的场景。 DFS 将 sz 初始化为 1，将 mn 和 mx 初始化为节点值。 由于条件检查 mn 等于 1 并且 mx 等于 sz，因此只有标记为 1 的节点通过。 提供的实现可以正确处理此问题，因为初始化和检查都发生在同一递归框架内。 

链状树强调递归深度。 每个节点都成为深度递归调用，但由于父指针阻止重新访问，因此每个节点仍然只处理一次。 该算法保持线性，并且保留了正确性，因为子树聚合不依赖于后序结构之外的遍历顺序。 

值与子树大小不对齐的情况演示了核心逻辑。 例如，包含值 {2, 3, 4} 的大小为 3 的子树会生成 mn = 2 和 mx = 4。尽管 mx - mn + 1 等于 3，但 mn 不等于 1，因此条件会正确拒绝它，从而防止仅基于区间的推理出现误报。
