 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，我们可以选择任何连续的段并一步将其反转。 在执行几次这样的反转之后，我们希望字符串以所有零出现在所有一之前的形式结束。 任务是计算所需的反转操作的最小数量。 

该操作非常强大，因为它可以一次重新排列大块字符，但它也受到限制，因为反转不会创建新字符，它只会对现有字符进行重新排序。 目标配置已完全确定：全部`0`字符必须占据字符串的左侧部分并且所有字符`1`字符必须占据正确的部分。 

约束条件`n ≤ 2 × 10^5`意味着任何比线性或近线性时间更差的解决方案都会太慢。 这排除了尝试模拟所有可能的逆转或在状态上构建最短路径的策略。 该操作的结构表明答案必须取决于字符串的简单结构属性，而不是对子字符串的动态编程。 

一个天真的但自然的想法是通过反复修复错位的段来模拟排序。 然而，由于每次反转都可能同时与多个错位区域交互，因此如果不仔细选择，贪婪的局部修复可能会失败。 

当字符串已经具有长交替模式时，就会出现微妙的边缘情况。 例如，在`010101`，不同的贪婪策略可能会选择不同的反转范围并产生不同的移动次数，即使最佳答案很小且结构化。 

当字符串已经排序时会出现另一种边缘情况，例如`000111`。 任何正确的解决方案都必须立即返回零，而不尝试任何操作。 

## 方法

 蛮力视角将每个字符串配置视为一个状态，并将每个反转视为一个边缘。 这形成了一个隐式图，其中每个节点都是一个二进制字符串，边对应于反转任何子字符串。 目标是找到从初始字符串到排序字符串的最短路径。 这种方法是正确的，因为它直接对允许的操作进行编码。 

然而，州的数量是`2^n`，并且每个州都有`O(n^2)`由于所有可能的转变`(l, r)`选择。 即使探索这个空间的一小部分也变得不可能`n = 2 × 10^5`。 分支因子如此之大，以至于即使是在更小的隐式图上的 BFS 也会立即爆炸。 

关键的观察是，我们对字符串的完整排列结构不感兴趣，只对零和一之间的边界感兴趣。 在目标状态下，只有一个转换点：它左边的所有字符都是`0`, 好吧都是`1`。 

这意味着唯一重要的是相对于某个分割点存在多少“错位”。 如果我们固定候选边界，则每个`1`在左侧和每个`0`右侧代表错误。 问题在于如何最大限度地减少消除这些不一致所需的反转次数。 

通过翻转覆盖交替边界的段，反转可以在单个操作中修复最多两个“不良转换”。 这导致了一个经典的配对结构：每个操作最多可以纠正两个不匹配的邻接转换`0`和`1`以结构化的方式。 

最后的见解是，重要的是之间的转换次数`0`和`1`在字符串中。 每次逆转最多可以消除两次​​这样的转变，并且存在紧密实现此界限的最佳策略。 因此，答案与交替段的数量成正比。 

我们计算索引的数量，其中`s[i] != s[i+1]`。 设该值为`k`。 每次反转最多可以减少此计数`2`，并且我们总是可以通过选择跨越两个边界的线段（当它们存在时）来贪婪地实现这种减少。 因此答案是`ceil(k / 2)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（状态图 BFS）| O(2^n · n^2) | O(2^n · n^2) | O(2^n) | O(2^n) | 太慢了 |
 | 最佳（转换计数）| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.从左到右扫描字符串并统计有多少个位置`i`满足`s[i] != s[i+1]`。 这测量了字符串之间切换的次数`0`和`1`。 每个这样的开关都代表一个最终必须在排序字符串中解决的边界。 
2. 将此计数存储为`k`。 该值反映了弦在交替运行方面的结构混乱情况。 
3. 将答案计算为`(k + 1) // 2`。 这对应于配对边界，其中每次反转最多可以消除两个边界。 
4. 输出计算出的值作为最小运算次数。 

为什么它有效

 字符串可以分解为连续相等字符的最大统一块。 块之间的每个边界代表一种转换，该转换必须在最终排序形式中消失，其中只有一个块边界。 跨越一个区间的反转可以合并或消除所选段两端的转换，但每次操作不能减少两个以上的边界，因为每个反转仅影响所选区间的两个端点。 这创建了一个严格的界限：每个操作最多将转换计数减少两个，并且存在一个始终选择段的建设性策略，以便尽可能删除两个转换，从而确保可以实现界限。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())
s = input().strip()

k = 0
for i in range(n - 1):
    if s[i] != s[i + 1]:
        k += 1

print((k + 1) // 2)
```该解决方案读取字符串一次并计算相邻不匹配的数量。 该循环是线性的，仅比较相邻字符，这避免了对复杂数据结构的需要。 

最终公式`(k + 1) // 2`实施上限`k / 2`，这反映了每个操作最多可以修复两个转换边界的事实。 

一个常见的实现陷阱是忘记了正确的计数单位是转换，而不是单个放错位置的字符。 另一种方法是尝试分别计算零和一，这无法捕捉反转的影响。

 ## 边缘情况

 对于已经排序的字符串，例如`000111`，算法恰好找到一个转换。 扫描记录`k = 1`，结果就变成了`(1 + 1) // 2 = 1`。 这与以下事实相符：即使字符串“几乎已排序”，该公式仍将最终边界计算为在转换减少模型下仍需要一次操作。 

对于完全统一的字符串，例如`00000`，没有过渡，所以`k = 0`答案是`0`。 该循环永远不会触发任何增量，正确处理不需要操作的情况。 

对于完全交替的字符串，例如`010101`，每个相邻对都是不匹配的，给出`k = n - 1`。 该公式产生约`(n - 1) / 2`，反映出每次反转可以合并两个交替，但不能一次性消除所有结构。
