 ## 解决方案
 ## 问题理解

 我们有一组学生，每个学生的 GPA 值在 0 到 5 之间。只有当学生的 GPA 经过可能的改进后达到至少 2.8 时，才被认为是“安全”的。 

有一种药水可以对学生多次使用，每次完整使用都会将该学生的 GPA 精确提高 1。但是，该药水很慢：每次使用都会消耗固定的时间，而我们的总时间预算有限。 重要的是，每个学生都必须独立提高，我们可以选择如何在学生之间分配药水使用。 

任务是在最佳利用可用时间后，尽量减少保持在 2.8 以下的学生数量。 同样，我们希望最大限度地提高可以培养的学生数量，达到至少 2.8，因为每次“升级”都有统一的时间成本，但不同的学生需要不同数量的升级。 

这些限制意味着我们必须将其视为可升级项目的资源分配问题。 对于典型的 Codeforces 规模输入（最多大约 10^5 名学生），对所有学生和药水分配的任何二次模拟都会太慢。 我们需要 O(n log n) 或 O(n) 策略，可能基于贪婪选择。 

一些边缘情况很重要：

 已经达到或高于 2.8 的学生需要零升级，并且应始终立即被视为安全。 例如，GPA 列表`[3.0, 4.2]`无论时间如何，未固化的产量都应为 0。 

略低于阈值的学生可能只需要一两次升级，而远低于阈值（例如 0.1）的学生可能需要更多升级。 首先优先考虑最低 GPA 的幼稚策略可能会失败，因为它可能会在早期将时间浪费在昂贵的转换上。 

另一个微妙的情况是，对于某些学生来说，即使进行一次升级，时间也不够。 如果总时间除以每次使用药水时间为零，则不可能有任何改进，答案就是 GPA < 2.8 的计数。 

## 方法

 暴力解释将模拟向学生分配魔药用途的所有可能方式。 对于每个学生，我们可以尝试应用 0, 1, 2, ... 升级到所需的限制，并递归地将剩余时间分配给其他学生。 这很快就会变成指数级的，因为每个学生都会引入多个分支选择，并且当 n 达到 10^5 时，即使考虑每个学生 10 个选择也会导致不可能的状态空间大小。 

关键的简化是观察到每个学生在药水使用方面都有一个固定的“成本”，达到 2.8。 如果学生有 GPA`a`，那么他们需要`ceil(max(0, 2.8 - a))`药水应用。 由于每个申请花费的时间相同`m`，问题简化为：每个学生都有一个权重（所需使用次数），并且我们有一个总使用次数的预算`k // m`。 我们希望最大化我们可以全额支付的重量。 

这是一个经典的贪心选择问题。 由于每个学生都会产生相同的“价值”（拯救一个人），但成本不同，因此我们应该始终优先考虑需要使用较少药水的学生。 按升序对所需用途进行排序可确保我们最大限度地增加完全治愈的学生的数量。

 | --- | --- | --- | --- |
 | 暴力破解（模拟分配）| 指数| O(n) | 太慢了|
 | 贪婪所需的升级| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 首先，计算每个学生需要使用多少药水才能达到阈值 2.8。 如果学生已经达到或高于 2.8，则该值为零。 

其次，通过将总可用时间除以每次药水使用时间来计算我们可以负担的总药水使用次数。 

第三，丢弃所有零申请的学生，因为他们已经治愈，不消耗资源。 

第四，按升序对剩余的所需应用计数进行排序，以便更便宜的治疗方法排在第一位。 

第五，迭代这个排序列表，并为每个学生检查我们是否还有足够的剩余药水申请。 如果是，减去他们的费用并将他们视为治愈。 否则，停止。 

最后，未治愈的学生人数就是剩余的学生人数减去我们成功治愈的学生人数。 

### 为什么它有效

 正确性依赖于贪婪交换论证。 假设我们选择了一位费用更高的学生，而跳过了一位我们本可以治愈的便宜学生。 交换它们永远不会减少治愈学生的数量，因为两者消耗相同的“价值”（一名治愈者），但更便宜的一个可以为其他人保留更多预算。 因此，任何最优解都可以转化为始终按照非递减成本顺序挑选学生而不损失最优性的解。 

这保证了贪婪选择在固定预算下最大化治愈的学生数量。 

## Python 解决方案```python
import sys
import math
input = sys.stdin.readline

def solve():
    m, k = map(int, input().split())
    n = int(input())
    
    # total potion uses available
    total_uses = k // m
    
    costs = []
    already_ok = 0
    
    for _ in range(n):
        a = float(input().strip())
        
        if a >= 2.8:
            already_ok += 1
            continue
        
        need = 2.8 - a
        # each use adds exactly 1 GPA
        uses = math.ceil(need)
        costs.append(uses)
    
    costs.sort()
    
    cured = 0
    for c in costs:
        if total_uses >= c:
            total_uses -= c
            cured += 1
        else:
            break
    
    print(n - (already_ok + cured))

if __name__ == "__main__":
    solve()
```该解决方案首先将总时间转换为药水应用的离散预算。 由于不允许部分申请，因此使用上限操作将每个 GPA 处理为所需的整数数量的申请。 

我们明确地将已经合格的学生分开，因为他们在不消耗任何预算的情况下为最终的安全计数做出了贡献。 剩下的学生会被转化为成本并进行分类，因此我们总是首先尝试最便宜的治疗方法。 

这个循环贪婪地消耗预算，确保我们在仍然可以处理更便宜的学生时永远不会将资源浪费在高成本的学生身上。 

一个微妙的细节是计算时的浮点处理`2.8 - a`。 由于输入最多保留一位小数，因此浮动精度在这里是安全的，但在更严格的设置中，使用缩放整数可以更好地处理。

 ## 边缘情况

 一个关键的边缘情况是所有学生都已超过阈值。 在这种情况下，成本列表为空，并且答案应该为零，而不执行任何排序或预算逻辑。 该算法自然地处理这个问题，因为`already_ok`等于`n`和`costs`是空的。 

另一种情况是预算允许零药水使用（`k < m`）。 然后`total_uses = 0`，而且费用清单上的学生都无法治愈。 最终答案正确地变成了低于 2.8 的学生人数，因为循环从未执行任何成功的扣除。 

当浮点值极其接近 2.8 时，会出现最后一种微妙的情况。 由于该问题使用十进制输入，因此计算`ceil(2.8 - a)`直接使用其他语言可能会面临精度问题。 该算法假设输入精度稳定，但在更稳健的实现中，将值缩放 10 或 100 将完全消除浮点问题。
