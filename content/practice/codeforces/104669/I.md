 ## 解决方案
 ## 问题理解

 我们从简化的 2048 游戏中获得了 4 x 4 的棋盘。 每个单元格包含零或二次方的图块。 零表示单元格为空。 棋盘通过应用移动而演变，但与原始游戏不同的是，不会出现新的图块。 

贝西反复应用固定的移动模式：首先向右移动，然后向下移动，然后再次向右移动，然后向下移动，如此下去。 每次移动都会沿该方向移动所有图块，压缩它们，并根据标准 2048 规则合并相等的相邻图块。 一个图块每次移动最多可以合并一次，合并方向优先于移动方向的远端。 

这个过程最终达到了这样一种状态：进一步的行动不再改变棋盘。 任务是输出最终的稳定配置。 

输出不是“经过一定数量的步骤”，而是重复应用向右和向下交替移动的固定点，直到没有任何变化。 

电路板尺寸恒定为 4 x 4，因此任何正确的模拟方法都可以承受重复的全网格转换。 即使是简单的模拟也很便宜，因为每次移动最多接触 16 个单元格，并且每行或每列的合并都是线性的。 唯一有意义的约束是合并规则的正确性和稳定性的正确检测。 

微妙的失败案例源于对稳定性的误解。 

一个常见的错误是假设如果正确的举措没有产生任何变化，那么该过程就完成了。 这是不正确的，因为稍后的下跌仍可能改变棋盘。 

另一个错误是将其视为单个“组合动作”或试图通过分析来预测最终配置。 右移和下移之间的相互作用可以不断解锁新的合并。 

第三个微妙的错误来自 2048 合并规则。 例如，在像这样的行中`[2, 2, 2, 2]`，正确移动后的正确结果是`[0, 0, 4, 4]`， 不是`[0, 0, 0, 8]`。 幼稚的双重合并实现会默默地破坏正确性。 

## 方法

 最直接的方法是完全按照描述模拟该过程。 我们反复应用向右移动，然后向下移动，直到棋盘不再发生变化。 

暴力解释可能会尝试模拟每个动作直到收敛，而不注意稳定的结构。 由于每次移动都是 O(16)，因此即使数千次迭代也可以忽略不计。 最坏的情况仍然在限制范围内，因为状态空间很小：每个单元仅采用 2 的幂到 2048 的值，因此不同配置的数量是有界的。 

关键的观察是我们不需要探索分支或寻找策略。 从我们重复应用两个固定变换的意义上来说，该过程是确定性和单调的。 一旦向右跟随向下的完整循环没有产生任何变化，进一步的循环也不会产生变化。 

因此，问题简化为重复应用两个函数，直到达到固定点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（模拟直到稳定，可能检查效率低下）| O(K·16) | O(1) | O(1) | 已接受 |
 | 最佳（具有适当移动功能的循环模拟）| O(K·16) | O(1) | O(1) | 已接受 |

 这里 K 是稳定之前的循环次数，在实践中它很小。 

## 算法演练

 我们定义了两个核心操作：右移和下移，每个操作在行或列上实现 2048 个机制。 

### 步骤

 1. 定义一个函数，通过过滤非零图块来处理给定方向上的单行（行或列）。 

此步骤很重要，因为 2048 在合并时会忽略空单元格。 
2. 在沿运动方向扫描的同时，每次移动合并一次相邻的相等值。 

当两个相等的图块相遇时，我们将它们组合起来并跳过下一个图块以强制执行“每次移动合并一次”规则。 
3. 将操作应用于所有行（右侧）或所有列（向下）后，重建完整的 4 x 4 网格。 

这保持了实现的对称性并避免了重复的逻辑。 
4. 重复以下循环：

 首先对网格应用向右移动，然后应用向下移动。 
5. 将生成的网格与之前的网格进行比较。 

如果两次操作后没有任何变化，则停止。 
6. 输出稳定的网格。 

### 为什么它有效

 该过程是确定性的，每次迭代都应用完全相同的转换序列：先向右，然后向下。 这定义了一个函数 F(grid)。 该算法重复计算 F 直到达到固定点。 

由于棋盘是有限的，并且每一步都是完全确定性的，一旦某个状态重复，系统就会进入一个循环。 然而，由于每个循环都严格地朝着无法在右/下规则下进一步压缩或合并的配置移动，所以唯一稳定的循环是 F(grid) 等于 grid 的固定点。 算法恰好在该状态停止。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

N = 4

def compress(line):
    """Apply 2048 merge rules to a single line moving right."""
    vals = [x for x in line if x != 0]
    res = []
    i = 0
    while i < len(vals):
        if i + 1 < len(vals) and vals[i] == vals[i + 1]:
            res.append(vals[i] * 2)
            i += 2
        else:
            res.append(vals[i])
            i += 1
    res = [0] * (N - len(res)) + res
    return res

def move_right(grid):
    return [compress(row) for row in grid]

def move_down(grid):
    cols = []
    for c in range(N):
        col = [grid[r][c] for r in range(N)]
        col = compress(col)
        cols.append(col)

    new_grid = [[0] * N for _ in range(N)]
    for c in range(N):
        for r in range(N):
            new_grid[r][c] = cols[c][r]
    return new_grid

def solve():
    grid = [list(map(int, input().split())) for _ in range(N)]

    while True:
        new_grid = move_right(grid)
        new_grid = move_down(new_grid)
        if new_grid == grid:
            break
        grid = new_grid

    for row in grid:
        print(*row)

if __name__ == "__main__":
    solve()
```该实现将核心逻辑分离为行压缩例程。 该函数是唯一执行 2048 规则的地方，这减少了行和列处理之间不一致的可能性。 

右移动直接按行应用。 向下移动是通过提取列、重用相同的压缩逻辑、然后写回网格来实现的。 这避免了重复的合并逻辑并确保方向之间的行为相同。 

停止条件比较完整的网格。 这很重要，因为一次向右移动可能不会改变棋盘，但随后的向下移动仍可能会改变棋盘。

 ## 边缘情况

 一种微妙的情况是，一行在向右移动后看起来没有变化，但在接下来的向下移动后发生了变化。 例如，所有图块已右对齐但垂直堆叠的配置在向下操作后仍会产生变化。 该算法处理这个问题是因为它总是在检查稳定性之前执行完整的循环。 

另一个边缘情况来自合并排序。 连续像`[2, 2, 2, 2]`，一个幼稚的实现可能会错误地产生`[0, 0, 0, 8]`。 正确的实现确保合并后跳过一次，这保留了每次移动块最多合并一次的规则。 

最后一个案例是振荡怀疑。 由于系统是确定性的，因此看起来可能会在没有稳定的情况下循环。 然而，由于每个周期严格地将图块推向固定方向的压缩，因此任何潜在的周期都会崩溃到一个固定点，并且完整周期后的停止检查会准确地捕获它。
