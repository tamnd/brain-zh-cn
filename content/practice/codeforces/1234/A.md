 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 在每个商店中，商店都有一份商品价格清单。 目标是用单一统一价格取代所有这些不同的价格，以便以该单一价格销售所有商品不会减少与原始定价相比的总收入。 

换句话说，如果原始总收入是所有给定价格的总和，我们要选择一个数字`x`使得销售`n`商品价格`x`每个给出总收入`n * x`，并且这必须至少是原始总和。 在所有这些有效值中`x`，我们想要尽可能小的一个。 

每个查询都是独立的，因此我们对每个测试用例重复此计算。 

限制很小：`n ≤ 100`和`q ≤ 100`。 这意味着即使在单个查询上具有立方或更差行为的解决方案仍然可能会通过。 然而，问题的结构表明我们应该避免不必要的模拟，而是寻找直接的数学条件。 

当所有值都相同时，就会出现一种幼稚但重要的边缘情况。 例如，如果所有价格都是`1`，则总计为`n`，最低统一价格也是`1`。 如果忽略全局约束，任何错误地尝试“匹配最大值”或“对每个元素进行舍入”的推理都可能会失败。 

当值变化很大时，就会出现另一个微妙的失败案例。 例如，`[1, 100, 100]`有总和`201`，正确的统一价格是`ceil(201/3) = 67`。 任何错误使用最大值或中位数的方法都会给出错误的答案，因为约束是关于总和，而不是单个值。 

## 方法

 思考这个问题的蛮力方法是尝试每一个可能的候选统一价格`x`。 对于每个`x`，我们检查是否`n * x ≥ sum(a_i)`。 最小的这样`x`就是答案。 自从`x`范围可以达到所有元素的总和，这可能需要迭代到大约`10^9`在最坏的情况下，即使约束很小，也是不必要的。 

关键的观察结果是条件仅取决于数组的总和。 一旦我们计算出来，原始收入就固定了`S = sum(a_i)`。 新的收入是`n * x`。 我们需要最小的整数`x`这样：`n * x ≥ S`这是一个简单的不等式。 满足它的最小整数是上限`S / n`。 

这将问题从搜索候选者转变为计算每个查询的单个算术表达式。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每个查询 O(S / n) | O(1) | O(1) | 概念上太慢|
 | 最佳| 每个查询 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们使用相同的推理独立地解决每个查询。 

1.读取商品数量`n`对于当前查询。 这定义了在总收入计算中将应用新的统一价格的次数。 
2. 读取价格数组并计算它们的总和`S`。 这代表我们必须匹配或超过的原始总收入。 
3. 计算最小整数`x`这样`n * x ≥ S`。 这相当于执行整数上限除法`S`经过`n`。 
4. 输出该值进行查询。 

唯一微妙的一步是整数上限除法。 我们不使用浮点除法，而是安全地将其计算为`(S + n - 1) // n`，这确保了正确性而没有精度问题。 

### 为什么它有效

 约束条件`n * x ≥ S`充分表征了有效性，因为统一后的收入仅取决于`x`以及物品的数量。 任何有效的解决方案都必须满足这个不等式，任何较小的值都会违反它。 由于函数`n * x`单调增加`x`，最小的有效整数恰好是`S / n`，使得该解决方案既必要又充分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        a = list(map(int, input().split()))
        s = sum(a)
        ans = (s + n - 1) // n
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案是围绕每个查询处理构建的。 总和计算是唯一有意义的聚合步骤，其他所有内容都简化为单个算术转换。 整数除法公式完全避免了浮点计算，即使对于大和也能确保正确性。 

## 工作示例

 ### 示例 1

 输入：```
n = 5
a = [1, 2, 3, 4, 5]
```我们计算总和`S = 15`。 

| 步骤| n | 总和S| 计算| 结果 |
 | ---| ---| ---| ---| ---|
 | 1 | 5 | 15 | 15 (15 + 4) // 5 | 3 |

 输出是`3`。 这证实了总收入`5 * 3 = 15`与原版完全一致。 

该轨迹显示了平等条件严格的情况，这意味着最优价格恰好保留了收入而不超过收入。 

### 示例 2

 输入：```
n = 3
a = [1, 2, 2]
```我们计算`S = 5`。 

| 步骤| n | 总和S| 计算| 结果 |
 | ---| ---| ---| ---| ---|
 | 1 | 3 | 5 | (5 + 2) // 3 | 2 |

 输出是`2`。 这里原来的和是 5，而`3 * 1 = 3`太小并且`3 * 2 = 6`就足够了。 

这说明了为什么需要四舍五入：下限会低估收入。

 ## 边缘情况

 一个关键的边缘情况是当`n = 1`。 该算法计算`(a1 + 0) // 1 = a1`，这是正确的，因为唯一可能的统一价格就是价值本身。 

另一种情况是所有值都相同。 如果`a = [k, k, ..., k]`， 然后`S = n * k`， 和`(S + n - 1) // n = k`，准确保留原始值。 

一个更有趣的情况是当值变化很大时，例如`a = [1, 100, 100]`。 这里`S = 201`， 和`n = 3`，因此计算得出`67`。 手动检查，`3 * 66 = 198`太小，而`3 * 67 = 201`满足要求，确认上限行为的正确性。
