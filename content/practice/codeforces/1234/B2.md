 ## 解决方案
 ## 问题理解

 我们正在模拟一个按“屏幕上出现的新近度”排序的动态对话列表，并对一次可以显示的对话数量设置了硬性上限。 每条传入消息都与一个好友 ID 相关联，并且每个 ID 恰好对应一次对话。 

当消息到达时，我们会检查该朋友的对话是否已在屏幕上可见。 如果不是，我们可能需要驱逐最近不可见的对话，以将总数保持在限制之内，然后我们在顶部插入新对话。 如果它已经可见，则根本不会发生任何变化，无论是顺序还是可见对话集。 

最终状态只是处理所有消息后按从上到下顺序排列的可见对话列表。 

这些限制允许最多 200,000 条消息，屏幕尺寸也最多为 200,000。 这立即排除了任何移动数组或线性搜索每条消息的解决方案。 扫描当前屏幕列表以查找成员资格，然后在 Python 列表中执行插入和删除的简单模拟在最坏的情况下会降级为二次时间，这远远超出了时间限制。 

一些边缘情况值得明确说明。 

例如，如果所有消息都来自同一个朋友`1 1 1 1`，那么在第一次插入后屏幕就不会再改变。 正确的解决方案必须避免在这种情况下重新插入或重新排序，否则会错误地重复推送相同的 ID。 

如果每条消息都来自不同的朋友并且`k = 1`，只有最新的唯一消息才应该保留。 用于输入`1 2 3 4`和`k = 1`，答案是`[4]`。 任何忘记正确驱逐或因未严格执行容量而保留旧项目的方法都会失败。 

另一个微妙的情况是重复交替，例如`1 2 1 2 1 2`和`k = 2`。 该结构会振荡，正确性取决于在恒定时间内正确检测当前屏幕状态的成员资格。 

## 方法

 直接模拟将屏幕维护为列表，并通过扫描查看 ID 是否已存在来处理每条消息。 如果不存在，我们会根据需要删除最后一个元素并插入到前面。 

这种方法是正确的，因为它准确地反映了规则，但在当前屏幕尺寸下，每个步骤都会花费线性时间。 超过`n`消息复杂度为 O(nk)，最坏情况下 k 为 O(n)，即 O(n²)。 当 n 达到 200,000 时，这太慢了。 

关键的观察是，我们需要两个操作才能快速：成员资格测试（“此 ID 当前是否可见？”）和维护最多 k 个元素的有序列表，其中我们经常将元素移动到前面，并可能删除最后一个元素。 

这正是 LRU 缓存的结构。 我们维持：

 - 双向链接订单（或Python`OrderedDict`) 表示从最近（前面）到最近（后面）的屏幕顺序。 
- 用于 O(1) 成员资格检查的哈希集或字典。 

当新消息到达时：

 - 如果它存在，我们什么都不做。 
- 如果不存在，则将其插入到前面，如果大小超过 k，则逐出最后一个元素。 

这将所有操作减少到摊销 O(1)，因为成员资格检查和重新排序都是所选数据结构中的常数时间操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nk) | O(nk) | O(k) | 太慢了 |
 | 最优（LRU 式结构）| O(n) | O(k) | 已接受 |

 ## 算法演练

 我们使用保留顺序并允许快速成员检查的结构来模拟屏幕。 在 Python 中，一个`OrderedDict`是理想的，因为它支持在恒定时间内插入、删除和重新排序。 

1. 初始化一个代表屏幕的空有序结构。 

该结构按照从最近到最近的顺序存储好友 ID。 
2. 按顺序遍历每个传入消息 ID。 

每个步骤都会更新可见对话的当前状态。 
3. 对于当前ID，检查它是否已存在于结构中。 

如果存在，则不执行任何操作，因为问题表明重复可见性不会更改顺序。 
4. 如果不存在，则将其插入到结构体的前面。 

这表示对话最近变得活跃。 
5. 如果结构体的大小超过k，则从后面移除最近的元素。 

这强制了屏幕容量限制。 
6.处理完所有消息后，按照从前到后的顺序输出结构。 

重要的部分是重新排序步骤。 当插入新 ID 时，它始终放置在前面，因为最新的消息定义了新近度排序，而不是频率或任何历史平均值。 

### 为什么它有效

 在任何时间点，该结构都会准确地维护在处理当前消息前缀后将出现在屏幕上的对话集。 排序不变性是，在所有可见对话中，最近插入或更新的对话始终位于前面，而最近插入或更新的对话位于最后。 由于只有新的未见过的 ID 会影响结构，而重复的 ID 不会起任何作用，因此现有元素之间的相对顺序仅在前面添加新元素时才会改变，这保留了新近度排序的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import OrderedDict

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))

    screen = OrderedDict()

    for x in arr:
        if x in screen:
            continue
        screen[x] = None
        screen.move_to_end(x, last=False)

        if len(screen) > k:
            screen.popitem(last=True)

    res = list(screen.keys())
    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```实现的核心是`OrderedDict`。 它同时处理成员资格检查、排序和高效更新。 这`move_to_end(x, last=False)`call 确保在前面插入，这是必要的，因为新对话必须始终是最新的。 

驱逐步骤`popitem(last=True)`当超出容量时删除最近的对话。 

一个常见的错误是在前面插入一个元素，即使它已经存在。 这会错误地更改新近度排序，但问题明确指出重复的消息根本不会修改屏幕状态。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每条消息最多触发一次字典查找、一次插入，可能还触发一次删除，全部 O(1) 摊销 |
 | 空间| O(k) | 该结构在任意时间最多存储 k 个活动对话 |

 这些约束允许最多 200,000 次操作，因此具有恒定时间更新的线性时间解决方案可以轻松满足时间和内存限制。 

## 测试用例```python
import sys, io
from collections import OrderedDict

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import OrderedDict

    n, k = map(int, input().split())
    arr = list(map(int, input().split()))

    screen = OrderedDict()

    for x in arr:
        if x in screen:
            continue
        screen[x] = None
        screen.move_to_end(x, last=False)
        if len(screen) > k:
            screen.popitem(last=True)

    res = list(screen.keys())
    return str(len(res)) + "\n" + " ".join(map(str, res))

# provided sample
assert run("7 2\n1 2 3 2 1 3 2\n") == "2\n2 1"

# all same values
assert run("5 3\n7 7 7 7 7\n") == "1\n7"

# k = 1
assert run("4 1\n1 2 3 4\n") == "1\n4"

# k equals n
assert run("3 3\n1 2 3\n") == "3\n3 2 1"

# alternating pattern
assert run("6 2\n1 2 1 2 1 2\n") == "2\n1 2"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 | 所有相同的值| 1 元素 | 重复的消息不会重新排序 |
 | k = 1 | 最后一个元素 | 严格驱逐行为|
 | k = n | 完全逆序| 满容量保持|
 | 交替模式| 稳定的二态 LRU | 会员资格和排序正确性|

 ## 边缘情况

 对于所有消息都相同的输入，例如`5 3 / 7 7 7 7 7`，第一个插入创建`[7]`，并且每个后续消息都会被忽略，因为 ID 已经存在。 该结构的大小永远不会超过 1，从而确认重复的消息不会导致重新插入或不必要的驱逐。 

为了`k = 1`， 例如`4 1 / 1 2 3 4`，每个新的未见过的 ID 都会替换之前的 ID。 处理后，只剩下最后一条消息。 该算法通过每当发生新插入时总是弹出最后一个元素来强制执行此操作。 

对于交替输入，例如`1 2 1 2 1 2`和`k = 2`，在前两次独特插入后屏幕稳定下来。 随后的重复不会干扰排序，这表明成员资格检查正确地阻止了已经可见对话的结构更新。
