 ## 解决方案
 ## 问题理解

 我们正在模拟智能手机聊天界面的行为。 智能手机屏幕最多可以显示$k$对话。 每条传入消息均来自由唯一 ID 标识的好友。 如果屏幕上已显示与该朋友的对话，则屏幕不会改变。 如果对话不在屏幕上，则将其插入顶部，如果屏幕已满，则删除底部的对话。 

输入给出$n$, 消息数量,$k$，屏幕容量，以及一系列$n$代表按顺序收到的消息的好友 ID。 输出是屏幕的最终状态：按从上到下的顺序显示的对话数量和 ID 列表。 

限制很小：$n, k \le 200$。 这意味着我们可以负担得起$O(nk)$算法不用担心效率。 不需要复杂的数据结构。 每个ID可以非常大（$1 \le id_i \le 10^9$），因此使用按 ID 索引的数组是不可行的。 相反，我们使用集合或列表来跟踪屏幕上出现的 ID。 

当消息频繁重复时，就会出现微妙的边缘情况。 例如，如果$n = 3$,$k = 2$，消息是$1, 1, 2$，一个幼稚的实现可能会插入第二个`1`再次，但规则指定如果对话已经可见，则重复项不会移动对话。 当唯一消息的数量永远不会超过时，就会出现另一种边缘情况$k$; 屏幕永远不需要驱逐对话，但算法必须正确维持秩序。 

## 方法

 蛮力方法很简单。 我们按顺序维护一个代表屏幕的列表。 对于每条传入消息，我们都会检查好友 ID 是否已在列表中。 如果是的话，我们什么也不做。 如果不是，我们将其插入前面。 如果列表超出大小$k$，我们删除最后一个元素。 这是简单且正确的，因为每个操作都直接遵循问题的规则。 其复杂度为$O(nk)$因为对于每个$n$我们可能需要搜索最多的消息$k$列表中的元素。 

进一步优化的关键见解是维护列表和集合。 该集合允许$O(1)$检查成员资格，同时列表保持顺序。 这减少了成员资格检查$O(k)$到$O(1)$，但在这个问题中，输入约束非常小，暴力方法已经可以接受。 问题结构-小$n$和$k$，并且插入总是在前面——使得简单的列表模拟足够高效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n*k) | O(k) | 已接受 |
 | 列表 + 设置 | O(n) | O(k) | 矫枉过正但也正确|

 ## 算法演练

 1.初始化一个空列表`screen`在屏幕上表示对话。 
2. 迭代每个消息ID`id_i`按照传入消息的顺序。 
3.如果`id_i`已经在`screen`，跳至下一条消息，因为屏幕没有变化。 
4. 否则，检查长度是否`screen`等于`k`。 如果是，则删除最后一个元素`screen`腾出空间。 
5. 插入`id_i`在前面`screen`表示它出现在最上面的位置。 
6. 处理完所有消息后，打印长度`screen`以及从上到下顺序排列的 ID。 

为什么它有效：列表`screen`始终代表当前对话的从上到下顺序。 不变式：不存在重复的ID`screen`它的大小永远不会超过`k`。 前面插入规则与满时从后面删除相结合可以保持正确的状态。 每个决策都直接遵循问题的规则，因此保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
ids = list(map(int, input().split()))

screen = []

for id_i in ids:
    if id_i in screen:
        continue
    if len(screen) == k:
        screen.pop()
    screen.insert(0, id_i)

print(len(screen))
print(' '.join(map(str, screen)))
```前两行有效地读取输入。 这`screen`list 保持从上到下的顺序。 对于每个`id_i`，我们首先检查是否有重复项。 如果屏幕已满，`pop()`删除底部对话。`insert(0, id_i)`在顶部添加新对话。 打印长度和内容`screen`完成模拟。 边缘情况，例如重复消息或唯一消息少于`k`自然由这些操作来处理。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    ids = list(map(int, input().split()))
    screen = []
    for id_i in ids:
        if id_i in screen:
            continue
        if len(screen) == k:
            screen.pop()
        screen.insert(0, id_i)
    return f"{len(screen)}\n{' '.join(map(str, screen))}"

# Provided samples
assert run("7 2\n1 2 3 2 1 3 2\n") == "2\n2 1", "sample 1"
assert run("4 3\n2 3 2 1\n") == "3\n1 3 2", "sample 2"

# Custom cases
assert run("3 2\n1 1 2\n") == "2\n2 1", "duplicate first"
assert run("5 3\n5 4 3 2 1\n") == "3\n1 2 3", "screen fills and evicts sequentially"
assert run("1 1\n10\n") == "1\n10", "single message fits screen"
assert run("6 6\n1 2 3 4 5 6\n") == "6\n6 5 4 3 2 1", "screen never full"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`3 2\n1 1 2\n`|`2\n2 1`| 处理重复消息而不重复 |
 |`5 3\n5 4 3 2 1\n`|`3\n1 2 3`| 屏幕反复填满时的驱逐令 |
 |`1 1\n10\n`|`1\n10`| 最小尺寸输入 |
 |`6 6\n1 2 3 4 5 6\n`|`6\n6 5 4 3 2 1`| 屏幕已满，但从未超过容量 |

 ## 边缘情况

 屏幕上已出现的重复消息将被跳过。 用于输入`3 2\n1 1 2`，第一个`1`插入后，第二个`1`被忽略，因为它已经可见，并且`2`被插入到顶部。
