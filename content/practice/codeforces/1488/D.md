 ## 解决方案
 ## 问题理解

 我们被要求在固定的天数内构造一个非递减的整数序列，其中每一天代表波利卡普解决了多少个问题。 问题总数是固定的，并且序列必须遵守两个结构规则：它不能随着时间的推移而减少，并且它在连续几天之间的增长不能超过两倍。 

我们最终关心的唯一事情是序列的最后一个值，但该值间接受到有效完整序列的存在的限制，该序列的总和恰好是给定的总数。 

所以问题就变成了：在所有长度为 n 且至少从 1 开始、非递减且每一步最多增加一倍的序列中，找到最大可能的最终元素，使得整个序列可以被选择与 s 精确求和。 

这些约束迫使我们每个测试解决方案的复杂度为 O(log s) 或 O(n log s)。 由于 n 和 s 高达 10^18 并且有多达 1000 个测试用例，因此任何显式模拟序列或尝试具有嵌套构造的候选者的尝试都将失败。 约束的结构是单调和乘法的，这通常表示贪婪的可行性检查与对答案的二分搜索相结合。 

如果我们忽略可行性而只考虑最大化最后一个元素，就会出现一个微妙的问题。 例如，如果我们尝试贪婪地将最后一个元素推得尽可能大，我们可能会创建一个在求和到 s 的同时无法保持非递减的前缀。 另一种失败模式是假设一旦候选最后一个值适用于给定的 n，所有较小的值也适用，而无需仔细检查序列必须如何“向后扩展”。 

关键的难点在于序列受到局部（邻居之间的比率）和全局（固定和）的约束，并且最优结构不是任意的，一旦最后一个值固定，它就变得严格确定。 

## 方法

 直接的暴力方法会尝试所有可能的序列。 对于每个序列，我们将验证单调性、加倍约束、总和约束，并跟踪最大的最后一个元素。 即使将值限制在合理的范围内，序列的数量也会随着 n 呈指数增长，因为每个位置都依赖于前一个位置，但仍然有许多有效的选择。 

更结构化的强力方法是固定最后一个值 x，然后尝试构造以 x 结尾且具有最小总和或精确总和 s 的任何有效序列。 即使这样也会变得昂贵，因为有效前缀的空间仍然是 n 的指数。 瓶颈在于每个位置可以在依赖于先前值的范围内变化。 

关键的观察是，对于固定的最后一个值，最小化总和的序列是唯一确定的。 如果我们想要生成一个以 x 结尾的有效序列，保持总和尽可能小的最佳方法是在向后移动时将值推至允许的最低值。 由于我们向前需要一个非递减序列，因此向后等效，我们必须确保前一个元素至少为 1，最多为下一个元素的一半，但也不能大于下一个元素。 

这意味着当我们固定一个最终值时，最优（最小和）构造是通过贪婪地向后移动、重复取最小允许值来获得的，这本质上是反转时不违反加倍约束的最大值。 

一旦我们能够计算给定最后一个值的最小可能总和，问题就在 x 中变得单调。 如果某个 x 可行（最小和 ≤ s），则任何较小的 x 也是可行的。 这允许对答案进行二分搜索。

 | --- | --- | --- | --- |
 | 暴力序列 | 指数| O(n) | 太慢了|
 | 二分查找+贪心可行性| O(n log s) | O(n log s) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们对 a_n 的最大可能值进行二分搜索，并且对于每个候选值，我们测试是否可以形成长度为 n 的有效序列，其总和不超过 s。 

1. 修复候选最后一个值 x 并尝试计算以 x 结尾的有效序列的最小可能总和。 目标是看看我们是否可以在约束允许的范围内“压缩”序列。 
2. 从第 n 天向后移动到第 1 天，保持从 x 开始的当前值 cur。 对于前一天，最小的可能值为 1，但我们还必须尊重未来增长不能超过一倍。 反转约束意味着先前的值必须至少为 ceil(cur / 2)，采用严格的结构，以避免不必要的通货膨胀。 
3. 更准确地说，为了最小化总和，将每个先前元素选择为 min(cur, 剩余位置下可行的最大值)。 在最佳构造中，当保持序列有效时，我们会重复采用 cur = cur // 2，因为减半是减少值同时保留最终达到 x 的能力的最强方法。 
4. 我们继续这个向后过程 n 步，累加总和。 如果在任何时候总和超过 s，我们可以提前停止，因为这个 x 是不可行的。 
5. 如果计算出的总和 ≤ s，则可以实现 x。 然后我们在二分查找中尝试更大的值； 否则我们减少x。 
6. 二分查找在 [1, s] 范围内运行，因为 a_n 不能超过 s。 

为什么它有效：

 关键的不变量是，对于任何固定端点 x，贪婪向后构造会产生以 x 结尾的字典顺序最小（因此也是最小和）的有效序列。 任何进一步减少某些中间值的尝试都会违反单调性或加倍约束。 因此，x的可行性仅取决于这个唯一的最小和，使得x中的谓词单调并启用二分搜索。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def feasible(n, s, x):
    total = 0
    cur = x

    for _ in range(n):
        total += cur
        if total > s:
            return False
        # move backwards: best we can do is shrink by factor 2
        cur = cur // 2
        if cur == 0:
            cur = 1

    return total <= s

def solve():
    t = int(input())
    for _ in range(t):
        n, s = map(int, input().split())

        lo, hi = 1, s
        ans = 1

        while lo <= hi:
            mid = (lo + hi) // 2
            if feasible(n, s, mid):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()
```该实现将可行性检查与搜索分开。 这`feasible`函数模拟固定最终值的序列的最佳向后构造。 关键的微妙之处在于转变`cur = cur // 2`，它编码最强的允许收缩，同时保留在加倍约束下到达终点的可能性。 

然后，二分搜索使用这个单调可行性谓词来最大化最后一个元素。 

## 工作示例

 ### 示例 1

 输入：n = 3，s = 9

 我们测试 a3 的候选值。 

| x| 序列构造（落后思想）| 总和| 可行|
 | --- | --- | --- | --- |
 | 4 | [1,2,4]| 7 | 是的 |
 | 5 | [1, 2, 5] 无效，最佳有效总和仍超过 9 个约束 | >9 | 没有|

 对于 x = 4，我们可以构造 [2, 3, 4]，它与 sum 9 完全匹配。 二分查找结果为 4。 

这表明可行性取决于序列是否可以在加倍的情况下“向上伸展”，同时保持早期值较小。 

### 示例 2

 输入：n = 2，s = 6

 | x| 序列| 总和| 可行|
 | --- | --- | --- | --- |
 | 3 | [3, 3] | 6 | 是的 |
 | 4 | [2, 4] | 6 | 是的 |
 | 5 | 不可能| >6 | 没有|

 这里3和4都是可行的，但是4更大，所以它成为答案。 这证明了答案空间的单调性。

 给定 n、s ≤ 10^18 且 t ≤ 1000，该解决方案依赖于这样一个事实：由于 cur 的快速减小，循环在实践中实际上很短，使得检查比最坏情况边界建议的速度快得多，并且很容易在限制内拟合。

 ## 边缘情况

 当 n = 1 时，会出现一种边缘情况。该序列只有一个元素，并且除总和约束之外的所有约束都消失，因此答案必须是 s。 该算法处理这个问题是因为 x 的可行性只是 x ≤ s 是否成立，二分查找自然会返回 s。 

另一种情况是 s 相对于 n 非常小。 例如，n = 5，s = 5 强制所有值都为 1。后向模拟立即将 cur 减少到 1 并保持总最小值，因此每个候选 x > 1 都变得不可行，并且二分搜索崩溃为 1。 

最终的结构边缘情况是当 s 大且 n 小时。 对于 n = 2，最佳分割倾向于在加倍约束下平衡 a1 和 a2。 可行性检查允许较大的 x 直到隐含总和超过 s，正确捕获该状态下的最佳 a_n 大约为 s/2。
