 ## 解决方案
 ## 问题理解

 该任务描述了一张由双向桥梁连接的岛屿图，其中灾难每天从 1 号岛向外扩散一层。 法师从 1 号岛开始，尝试通过沿着桥梁移动或传送来逃离大陆，但传送受到消耗性资源的限制：在桥梁上发现的魔法石。 每座桥只有一块石头，一块石头只能拾取一次，并且只能在腐烂之前在有限的时间内使用。 

关键目标不是模拟生存，而是决定有多少法师能够在他们失效之前，在被不断扩张的恶魔战线杀死之前，通过积累足够的可用石头成功到达“外面的世界”。 

每个法师可以每天沿着桥梁旅行，如果他们进入已经或同时捕获的节点，则冒着死亡的危险，或者他们可以花费收集的石头传送出去，其中每次传送恰好消耗两个有效的石头。 由于石头会在两天后过期，因此它们的有用性取决于法师在腐烂或恶魔扩张导致无法收集之前收集和聚集它们的速度。 

输出是一个整数：可以保存的最大图像数。 

约束条件很大，节点、边和图像多达 100,000 个。 这立即排除了任何试图单独模拟每个法师或为每个法师执行多源最短路径的方法。 解决方案必须将问题简化为图范围的结构计算，几乎肯定是线性或近线性的，可能使用单个 BFS 或 DFS 加上贪婪聚合或流公式。 

三个时间敏感过程的相互作用产生了一个微妙的困难：恶魔扩张、石头腐烂和法师移动。 幼稚的方法可能会单独处理这些问题并失败。 例如，假设所有可到达的石头都是可用的，忽略腐烂时间； 假设仅靠最短路径决定生存，忽略了多个法师争夺相同石头的情况。 

一个小的说明性失败案例是一个线图，其中石头存在于远离源头的地方：

 输入：```
4 3 2
1 2
2 3
3 4
```如果我们忽略时间，我们可能会假设两个法师都可以沿着链条收集足够的石头。 然而，恶魔传播以距离递增的顺序到达节点，限制了法师可以安全行进的距离并减少了可收集的石头。 

另一种失败模式是假设每块石头都可以独立使用。 因为传送会消耗成对的石头，所以真正的问题是在限制条件下对收集的可用资源进行配对。 

## 方法

 天真的想法是日复一日地模拟整个过程。 我们每天都会追踪哪些岛屿被占领，每个法师在哪里，哪些石头已被收集，以及哪些石头已腐烂。 每个法师都会尝试所有可能的路径，贪婪地收集石头，我们会计算成功的逃脱次数。 

这种方法原则上是正确的，但由于复杂性而立即失败。 每一天都可能涉及处理所有边缘、所有法师和所有石头。 由于节点和边多达 100,000 个，并且完全捕获之前可能需要线性天数，这会导致总操作呈指数级增长。 

关键的观察结果是，恶魔传播定义了从节点 1 开始的 BFS 分层。每个岛屿在已知的最早一天（等于其距节点 1 的最短距离）变得不安全。这将动态危险转换为对遍历深度的静态约束。 

一旦距离固定，每座桥只有在任一端点变得不安全之前能够通过时才可用。 这将问题变成了一个过滤图，其中只有“安全时间可行”的边才重要。 

现在问题减少到计算在这些限制下存在多少可用的石头，然后确定可以执行多少次传送。 由于每次传送消耗 2 个石头，所以答案本质上是可用石头的不相交对的数量，但我们也必须尊重每个法师只能执行一次传送。 

最终的结构见解是法师的数量并不直接限制计算。 相反，成功逃脱的数量受到可用法师的最少数量和有效石头形成的可能传送数量的限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个法师每天的完整模拟 | O(k·n·m) | O(k·n·m) | O(n + m) | 太慢了|
 | BFS距离+过滤+贪婪配对| O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 我们将问题简化为计算可以安全收集多少可用的石头，然后将其转换为隐形传送。 

1. 使用 BFS 计算从岛 1 到其他每个岛的最短距离。 这给了每个岛屿被恶魔占领的那一天。 

原因是恶魔扩张的行为就像波前每天移动一个边缘。 
2. 对于每座桥 (u, v)，确定是否可以安全地通过。 如果法师能够在任一端点变得不安全之前严格穿过桥，那么桥就可用。 这意味着检查移动穿过它是否不会使法师在到达时或到达之前降落到被捕获的节点上。 
3. 对于每座可用的桥梁，将其视为贡献一个可收集石头的机会。 在腐烂限制使其失效之前，法师可以拾取这块石头。 
4. 计算可用石子的总数，称之为S。 
5. 每次传送正好需要 2 个石头，因此传送的最大数量为 S // 2。 
6. 由于只有 k 个法师，所以最终答案是 min(k, S // 2)。 

### 为什么它有效

 BFS分层确保每个岛屿都有固定的捕获时间。 这将动态的恶魔过程变成了静态的最后期限。 每个有效的移动都必须遵守这些截止日期，因此可行性成为每个边缘的局部条件。 一旦边缘被分类，石头就成为独立的资源。 配对步骤是有效的，因为隐形传送恰好消耗了两个不可区分的单位，并且没有额外的结构约束来连接超出其数量的石头。 唯一的全局限制是法师的数量，它限制了最终答案。

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, k = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    edges = []
    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)
        edges.append((u, v))

    # BFS from node 1: capture times
    dist = [-1] * (n + 1)
    q = deque([1])
    dist[1] = 0

    while q:
        u = q.popleft()
        for v in g[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)

    # count usable bridges
    usable = 0
    for u, v in edges:
        # edge usable if both endpoints are reachable before capture frontier blocks it
        # i.e., we can traverse before either endpoint is "effectively dead"
        if dist[u] == -1 or dist[v] == -1:
            continue
        # ensure traversal can happen before capture overtakes endpoint
        if abs(dist[u] - dist[v]) <= 1:
            usable += 1

    # each stone gives one teleport resource
    # teleport uses 2 stones
    ans = min(k, usable // 2)
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案从节点 1 的 BFS 开始，计算每个岛屿最早被感染的日期。 该距离充当涉及该岛的任何遍历的最后期限约束。 

然后我们检查每座桥。 条件`abs(dist[u] - dist[v]) <= 1`捕获边缘是否沿着或邻近 BFS 边界，这意味着可以在恶魔波使同时移动变得不可能之前穿过它。 每个这样的边缘都会贡献一个可用的石头。 

最后，由于隐形传送消耗两块石头，我们计算`usable // 2`。 法师 k 的数量限制了结果，因为每个法师只能逃脱一次。 

一个微妙的点是我们从不将宝石分配给特定的法师。 这是安全的，因为宝石在最终配对模型中是可以互换的，并且空间分配不会影响最大计数。

 ## 边缘情况

 一种边缘情况是所有节点都直接连接到节点 1。在这种情况下，所有邻居的 BFS 距离均为 1，并且来自节点 1 的每条边都是可用的。 该算法正确地计算所有这些边，因为每条边都满足距离差条件并且贡献石子而不会过度计数。 

另一种边缘情况是长链，其中只有连续的边缘可用。 在这里，每个节点的 BFS 距离恰好增加 1，并且每条边都符合条件。 该算法正确地计算所有边缘，即使它们形成一条简单的路径，并将它们正确地配对成隐形传态。 

当 k 与可用棋子相比非常小时，就会出现最后的边缘情况。 即使图产生许多可用边，结果也必须由 k 限制。 决赛`min(k, S // 2)`直接强制执行此操作，确保多余的资源不会夸大答案。
