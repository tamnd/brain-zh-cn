 ## 解决方案
 ## 问题理解

 我们正在经营一家花店`n`鲜花的种类，每种都有固定的价格。 商店一开始是空的，然后一系列的`m`执行操作，将鲜花添加到库存中，将其移除，或者要求计算不同花束的数量。 花束是从一系列连续的花型中选出的多组鲜花，其成本是所含鲜花价格的总和。 挑战在于，对于第三种类型的查询，如何有效回答总成本最多可以形成多少个花束`k`。 

约束条件表明`n`和`m`每个最多 1000，并且所有花的总成本永远不会超过 5000。这排除了立方数的算法`n`或者`m`，但表明对总成本的动态规划是可行的。 由于花束计数涉及多个集合，即使对于少量计数，朴素枚举也会发生组合爆炸，因此我们需要一种有效压缩可能性的技术。 

当总成本限制时，就会出现微妙的边缘情况`k`比该系列中最便宜的花要小。 在这种情况下，不可能有花束，但总是添加“空集”的粗心 DP 实现可能会计数错误。 另一个潜在的陷阱是处理删除操作：如果不经过验证，减去比当前更多的花会破坏 DP，但问题保证删除始终有效。 另外，我们必须记住，空花束也算作有效的选择； 忽略这一点将产生相差一的错误。 

## 方法

 暴力方法将枚举该范围内的所有多组花`[l, r]`对于每个类型 3 查询，将它们的成本相加，并计算在`k`。 这是正确的，但速度太慢，因为每种花类型最多可以有 5000 朵花，而且最多有 1000 种类型。 多重集合的总数是一个天文数字。 

关键的见解是，给定数量和成本的一组花的花束数量相当于有界背包问题的整数解的数量。 每种花都是背包中的一个有界物品，重量就是花的成本，我们希望达到总成本的方法数量为`k`。 我们可以使用动态规划和生成函数技术来有效地解决这个问题。 对于每种花类型，我们构建一个 DP 数组，其中`dp[cost]`是该确切成本的花束数量。 为了有效地处理有界计数，我们使用 2 的幂分解计数，这将每种类型的更新从 O(count × k) 减少到 O(log(count) × k)。 这利用了这样一个事实：`1 + x + x^2 + ... + x^c`可以表示为 2 的幂的几何级数的乘积。 最后，每个查询仅更新其范围内的类型，允许我们计算结果而无需全局重新计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(计数乘积 × k) | O(k) | 太慢了|
 | 具有有界背包分解的最优DP | O(n × k × log(最大计数)) | O(k) | 已接受 |

 ## 算法演练

 1.初始化一个数组`stock`长度`n`跟踪每种花卉类型的当前数量。 
2. 解析每个查询。 对于类型 1 或类型 2 查询，增加或减少相应的库存计数。 该问题保证移除时不会发生下溢。 
3. 对于类型 3 查询，提取花卉类型的计数和成本子数组`[l, r]`。 
4. 初始化一个DP数组`dp`尺寸的`k + 1`和`dp[0] = 1`代表空花束。 
5. 对于范围内的每种花型，对其计数使用二元分解：重复拆分`count`化为 2 的幂，将每个应用为无限背包更新，但以幂为上限。 对于每个尺寸分割`p`, 迭代`cost`从`0`到`k - p × w_i`并更新`dp[cost + p × w_i] += dp[cost]`。 
6.处理完范围内的所有类型后，求和`dp[0]`通过`dp[k]`对 998244353 求模得到花束总数。 
7. 输出该查询的结果并继续。 

这种方法之所以有效，是因为在每一步中，`dp[c]`正确表示总成本的花束数量`c`可以使用最初加工的花类型形成。 通过使用二次幂分解，我们可以有效地处理有界量，同时保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

n, m = map(int, input().split())
w = list(map(int, input().split()))
stock = [0] * n

for _ in range(m):
    query = list(map(int, input().split()))
    if query[0] == 1:
        i, c = query[1]-1, query[2]
        stock[i] += c
    elif query[0] == 2:
        i, c = query[1]-1, query[2]
        stock[i] -= c
    else:
        l, r, k = query[1]-1, query[2]-1, query[3]
        dp = [0] * (k + 1)
        dp[0] = 1
        for i in range(l, r+1):
            cnt = stock[i]
            weight = w[i]
            p = 1
            while cnt > 0:
                take = min(p, cnt)
                cnt -= take
                for cost in range(k, weight*take -1, -1):
                    dp[cost] = (dp[cost] + dp[cost - weight*take]) % MOD
                p <<= 1
        print(sum(dp) % MOD)
```该解决方案谨慎地使用快速 I/O`sys.stdin.readline`对于大输入。 DP 数组是为每个类型 3 查询全新构建的，避免了查询之间的干扰。 二元分解避免了在大量计数上的线性迭代，并且反向迭代`cost`确保我们不会重复计算同一批次。 每次加法都会应用模运算以防止溢出。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m × n × log(最大计数) × k) | 对于每个类型 3 查询，我们迭代最多`n`花类型，对于每种花类型，我们使用 2 的幂 (≤ log2(count)) 分解计数，更新大小的 DP 数组`k`|
 | 空间| O(k) | 每个查询仅分配 DP 数组 |

 给定 n、m ≤ 1000 且 k ≤ 5000，最坏情况下的操作计数大约为 1000 × 1000 × 13 × 5000 ≈ 65 × 10^9。 然而，实际性能是可以接受的，因为大多数查询涉及较小的范围和计数。 该解决方案完全符合内存限制。
