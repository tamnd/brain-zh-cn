 ## 解决方案
 ## 问题理解

 正好有 (N) 个房间，编号从 (1) 到 (N)，并且正好有 (N) 个参与者。 参与者 (i) 的护照号码为 (a_i)。 我们可以选择将参与者一对一分配到房间。 

如果参与者的护照号码与他们收到的房间号码完全相同，则参与者会创建匹配。 任务是最大化此类匹配的数量。 

关键限制是每个房间只能容纳一名参与者。 假设护照号码 (x) 出现多次。 如果 (x) 是有效的房间号，则最多有一个参与者可以贡献一场比赛，因为只有一个房间号为 (x)。 另一方面，如果护照值 (x) 至少出现一次并且 (1 \le x \le N)，我们总是可以将持有该护照的一名参与者放入房间 (x)。 不同的护照值对应不同的房间，因此所有这些值可以同时匹配。 

因此，答案正是位于区间 ([1,N]) 内的不同护照值的数量。 

(N) 的值可以达到 (10^5)，因此具有二次复杂度的算法在最坏的情况下已经需要大约 (10^{10}) 次运算，远远超出了典型的竞争性编程时间限制可以处理的范围。 护照号码可以达到（10^9），因此分配以护照号码索引的数组也是不合适的。 我们需要一种方法，其工作接近 (N) 中的线性，同时仅存储实际发生的值。 

有几种边缘情况可能会欺骗粗心的实施。 首先，重复的护照号码只能计算一次。 例如，```
4
1
1
2
2
```有答案`2`，因为尽管有四名护照值匹配的参与者，但只能匹配房间 1 和 2。 计算该范围内的每本护照将错误地产生`4`。 

其次，大于（N）的护照号码永远无法匹配任何房间。 例如，```
3
1
3
100
```有答案`2`。 护照`100`无法匹配，因为没有房间 100。 

第三，边界值（N）是有效的并且必须包括在内。 为了```
1
1
```答案是`1`。 使用严格条件的实现，例如`a_i < N`会错误地返回零。 

最后，一些参与者的护照号码可能都在房间范围之外。 例如，```
4
1000000000
1000000000
1000000000
1000000000
```有答案`0`。 重复项并不重要，并且没有一个值对应于可用房间。 

## 方法

 直接的暴力方法是考虑参与者到房间的每一种可能的分配。 参与者有 (N!) 种排列，对于每个作业，我们可以检查 (N) 个房间并计算有多少护照号码与他们的房间号码相匹配。 这是正确的，因为每一种可能的座位安排都会被检查，所以必须找到最好的座位安排。 然而，最坏情况的工作是 (N \cdot N!)。 即使在 (N=10) 下，这也已经是 (36{,}288{,}000) 次房间检查，而 (N=10^5) 则使该方法完全不可行。 

匹配条件的结构为我们提供了一种更简单的方式来思考问题。 当至少一名参与者拥有护照号码 (x) 时，就可以在房间 (x) 进行比赛。 由于只有一间房间的编号为 (x)，因此具有相同护照号码的多个参与者不会创建多个可能的匹配。 唯一重要的信息是每个房间号是否在护照号码中至少出现一次。 

因此，我们扫描护照号码并收集 (1) 和 (N) 之间的不同值。 每个收集的值对应一个不同的房间，并且可以将一名携带该护照的参与者放置在那里。 相反，超出此范围的护照值不能产生匹配，并且相同值的重复出现不能产生额外的匹配。 

因为护照号码可以大到（10^9），Python`set`是一种自然的表征。 它仅存储实际发生的值，并提供预期的恒定时间插入和成员资格操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(N \cdot N!)) | (O(N)) | 太慢了 |
 | 最佳| (O(N)) 预期 | (O(N)) | 已接受 |

 ## 算法演练

 1. 读取（N），房间数和参与者数。 
2. 创建一个空集，名为`matched`。 
3. 读取每个护照号码 (a_i)。 如果(a_i)在(1)和(N)之间，则将其插入`matched`。 

上限是唯一有趣的检查，因为所有护照号码都已保证至少为 (1)。 大于(N)的值没有相应的空间，而等于(N)的值是有效的，必须保留。 
4.处理完所有参与者后，输出大小`matched`。 

该集合中的每个值代表一个不同的房间，参与者可以使用该护照号码来填充该房间。 由于所有这些房间号都是不同的，因此所有这些比赛都可以共存于一个座位安排中。 

### 为什么它有效

 考虑任何护照价值 (x)`matched`。 它发生在参与者之间并满足(1 \le x \le N)，因此有一个编号为(x)的房间。 我们可以将一名持有护照 (x) 的参与者放入该房间并获得一场比赛。 由于集合中的不同值对应于不同的房间，因此可以同时对集合中的每个值执行此操作。 

现在考虑任何座位安排。 仅当参与者的护照值为房间号时才会发生匹配，因此该值必须位于 ([1,N]) 中。 如果多个参与者共享相同的护照值 (x)，则最多可以匹配一个，因为只有一间房间有编号 (x)。 因此，任何安排都不能包含比不同有效护照值的数量更多的匹配项。 

该算法准确地构造了一组不同的有效值，因此其大小既是可实现的，也是一个上限。 因此，这是最大可能的匹配数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    matched = set()

    for _ in range(n):
        x = int(input())
        if x <= n:
            matched.add(x)

    print(len(matched))

if __name__ == "__main__":
    solve()
```这`matched`set 直接对应于算法第 2 步中构造的集合。 每份输入护照均被处理一次，并且`add`自动处理重复项，因此没有单独的频率数组或排序步骤。 

条件`x <= n`是足够的，因为问题保证 (x \ge 1)。 使用`x < n`将是一个差一错误，因为房间 (N) 存在。 (10^9) 以内的值对于 Python 整数来说是无害的，并且涉及护照值的算术不会溢出。 

该解决方案不需要存储整个输入数组。 一旦将通行证值插入集合中，其原始参与者索引就不再相关。 这使实现变得简单，并且仅使用确定答案所需的信息。 

问题中只有一个测试用例，因此程序准确读取 (N) 个护照号码。 使用`sys.stdin.readline`提供适合（N=10^5）的快速输入。

 ## 边缘情况

 对于重复的护照号码，请考虑```
4
1
1
2
2
```该算法从一个空集开始。 第一个`1`创造`{1}`，第二个`1`保持不变，第一个`2`创造`{1, 2}`，以及最后的`2`也保持不变。 结果是`2`。 这正是最大值，因为房间 1 和 2 是唯一可以产生比赛的房间，并且每个房间只能包含一名参与者。 

对于护照价值超出房间范围的情况，请考虑```
3
1
3
100
```价值`1`被插入是因为房间 1 存在。 价值`3`被插入是因为房间 3 存在。 价值`100`被忽略，因为最大的房间号是 3。最终的集合是`{1, 3}`，给出答案`2`。 护照100的参与者无论如何安排都无法匹配任何房间。 

对于上边界，考虑```
1
1
```这里（N=1），所以护照`1`满足`x <= n`并插入到集合中。 它的大小是`1`，这意味着唯一的参与者可以被放入唯一的房间并产生匹配。 这会捕获意外使用严格不等式的实现。 

对于最大可能的输入大小，请考虑 100000 名护照为`1000000000`。 每个值都不满足条件`x <= n`因为 (10^9 > 10^5)，所以该集合在整个扫描过程中保持为空。 答案是`0`。 该算法仍然只对每个参与者执行一次简单的检查，因此将 (N) 增加到最大值不会改变渐近行为。
