 ## 解决方案
 ## 问题理解

 正好有 (N) 个房间，编号从 (1) 到 (N)，并且正好有 (N) 个参与者。 参与者 (i) 的护照号码为 (a_i)。 我们可以选择将参与者一对一分配到房间，当参与者的护照号码等于他们收到的房间号码时，他们就会创建匹配。 

任务是最大化匹配的数量。 大于 (N) 的护照号码永远不会产生匹配，因为没有空间容纳该号码。 对于护照号码 (x) 为 (1 \le x \le N) 的情况，只能将一名参与者放入房间 (x)，因此 (x) 的重复项无法创建多个匹配项。 

关键的结果是，区间 ([1,N]) 中的每个不同的护照号码恰好贡献了一个可能的匹配。 我们只需要计算数组中出现了多少个与该区间不同的值。 

对于线性或 (O(N\log N)) 算法来说，界限 (N \le 10^5) 足够小，但它排除了典型竞争性编程时间限制下的 (O(N^2)) 方法。 在 (N=10^5) 处，二次扫描可以执行大约 (10^{10}) 次比较，这远远超出了实际情况。 护照号码可以达到（10^9），因此分配以护照号码索引的数组会浪费大量内存。 哈希集是一个自然的选择，因为它只存储实际出现的值。 

在某些情况下，粗心的实施可能会产生错误的答案。 首先，重复项必须计算一次。 用于输入```
5
1
3
5
7
5
```答案是（3），而不是（4），因为房间（1）、（3）和（5）可以匹配，而持有护照（5）的两个参与者竞争同一个房间。 

其次，房间范围之外的值必须被忽略。 为了```
4
1000000000
1000000000
1000000000
1000000000
```答案是（0），因为没有房间有编号（10^9）。 

第三，边界值（N）是有效的并且必须包括在内。 为了```
3
1
2
3
```答案是（3）。 检查的实现`a[i] < N`而不是`a[i] <= N`会错误地返回 (2)。 

最后，最小的房间范围必须正常工作。 为了```
1
1
```答案是（1），而对于```
1
2
```答案是（0）。 这些情况暴露了有效间隔端点周围的错误。 

## 方法

 一种直接的方法是考虑每个房间并在所有参与者中搜索护照与该房间号相同的人。 对于每个房间 (r)，我们扫描 (N) 护照号码并检查某些参与者是否拥有护照 (r)。 如果存在这样的参与者，我们就算一场比赛。 这是正确的，因为每个房间只能容纳一名参与者，因此至少有一名持有护照 (r) 的参与者的存在足以使房间 (r) 贡献一场比赛。 

问题是工作量。 有 (N) 个房间，每个房间可能需要检查 (N) 个参与者，进行 (N^2) 次比较。 在 (N=10^5) 时，最坏情况下是 (10^{10}) 次比较，这太慢了。 

改变问题的观察结果是，一旦我们知道护照号码是否出现，参与者的身份就不再重要了。 对于从 (1) 到 (N) 的每个房间号 (r)，当 (r) 在护照号码中至少出现一次时，答案恰好为 1。 同一 (r) 多次出现并无帮助，因为房间 (r) 只能包含一名参与者。 

我们可以用一组来表示所有出现过的护照号码。 在读取输入时，我们仅插入满足 (1 \le a_i \le N) 的值。 最后，集合的大小正是匹配参与者存在的房间数量。 

这两种方法可以总结如下。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(N^2)) | (O(1)) | (O(1)) | 太慢了 |
 | 最佳 | (O(N)) 预期 | (O(N)) | 已接受 |

 ## 算法演练

 1. 读取 (N) 并创建一个空集，称为`seen`。 该集合将包含与一个房间相对应的每个护照号码，并自动删除重复的护照号码。 
2. 读取 (N) 个护照号码。 如果一个值(a_i)满足(1 \le a_i \le N)，则将其插入`seen`。 大于 (N) 的值永远无法匹配任何房间，因此没有必要存储它们。 
3.所有参与者处理完毕后，输出`len(seen)`。 该集合中的每个值对应于一个不同的房间号，可以通过将具有该护照号的参与者分配到相应的房间来匹配该房间号。 

为什么所有这些比赛能够同时实现？ 假设该集合包含 (k) 个不同的有效护照号码。 每个人都对应一个不同的房间号，因此我们可以为每个不同的护照价值选择一名参与者，并将该参与者放入其匹配的房间。 这些参与者是不同的，因为一名参与者只有一个护照号码，不同的护照号码不能属于同一参与者。 剩余的参与者可以任意分配到剩余的房间。 

### 为什么它有效

 处理参与者的任意前缀后的不变量是`seen`包含与房间范围 (1) 到 (N) 中的前缀完全不同的护照号码。 最后，对于每个房间 (r)，当至少一个参与者拥有护照 (r) 时，该集合恰好包含 (r)。 如果 (r) 存在，则可以将一个这样的参与者分配到房间 (r)，从而产生一场比赛。 如果 (r) 不存在，则任何分配都无法使房间 (r) 匹配。 由于不同的值`seen`对应不同的房间，所有这些可能的匹配都可以一次实现。 因此，集合的大小正是最大可能的匹配数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    seen = set()

    for _ in range(n):
        passport = int(input())
        if passport <= n:
            seen.add(passport)

    print(len(seen))

if __name__ == "__main__":
    solve()
```第一行读取房间和参与者的数量。 该集合最初是空的，与处理任何护照号码之前的状态相匹配。 

对于每个参与者，代码都会检查`passport <= n`。 护照号码保证至少为 (1)，因此无需显式测试下限。 必须接受等于 (n) 的护照，这就是比较的原因`<=`而不是`<`。 

呼唤`seen.add(passport)`handles duplicates automatically. 如果五名参与者拥有护照（5），则该集合仍然仅包含一份（5）副本，这与只有其中一人可以占用房间（5）的事实完全匹配。 

Python 中不存在整数溢出问题，最大的护照值 (10^9) 直接由整数类型处理。 更重要的是，我们从不尝试分配大小为 (10^9) 的数组，因此大的 Passport 范围对内存使用没有负面影响。 

决赛`len(seen)`是答案，因为每个存储的值都对应于一个不同的可实现的房间匹配。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(N)) 预期 | 每个护照被读取一次并在预期的恒定时间内插入到哈希集中。 |
 | 空间| (O(N)) | 最多可以存储 (N) 个不同的护照号码。 |

from contextlib import redirect_stdout

def solve():
    n = int(input())
    seen = set()

    for _ in range(n):
        passport = int(input())
        if passport <= n:
            seen.add(passport)

    print(len(seen))

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    output = io.StringIO()

    try:
        with redirect_stdout(output):

 ## 边缘情况

 第一个极端情况是护照号码重复。 考虑```
5
1
3
5
7
5
```该算法将 (1)、(3) 和 (5) 插入到集合中。 护照 (7) 被丢弃，因为没有空间 (7)，第二本护照 (5) 保持不变，因为 (5) 已经存在。 结果是(3)。 关键属性是该集合代表可以匹配的房间，而不是可以匹配的参与者。 

第二个边缘情况是房间范围之外的护照号码。 和```
4
1000000000
1000000000
1000000000
1000000000
```每个值都失败`passport <= n`查看。 该集合仍然为空，因此结果为 (0)。 这可以避免不正确的匹配和不必要的不​​相关值的存储。 

第三个边缘情况是上边界。 为了```
3
1
2
3
```该算法接受所有三个值，因为 (1 \le a_i \le 3)。 该集合变为`{1, 2, 3}`，给出答案（3）。 条件必须包含与 (N) 相等，否则房间 (N) 将被错误排除。 

有效匹配的最小情况是```
1
1
```这里（N=1），护照（1）通过了范围检查。 该集合变为`{1}`，所以答案是（1）。 对于密切相关的输入```
1
2
```护照 (2) 比唯一的房间号大，因此集合保持为空，答案为 (0)。 

最大尺寸的箱子可包含 (100000) 个相同的护照号码。 该集合仍然只存储一个值，而算法只对输入执行一次传递。 这说明了为什么即使参与者数量达到最大值，解决方案仍保持线性。
