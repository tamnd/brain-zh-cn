 ## 解决方案
 ## 问题理解

 我们得到一个非空的十进制字符串，没有前导零。 该字符串不一定以基数 10 进行解释。我们可以选择基数 (B)，前提是字符串中出现的每个数字都是该基数中的有效数字。 解释基数 (B) 中的相同数字序列会产生一些整数 (D)。 

我们的任务是选择 (B) 和 (D) 的适当约数 (X)，其中 (1 < X < D)，使得 (B) 和 (X) 都至多为 (10^9)。 如果不存在这样的对，我们打印 (-1)。 

长度可以达到(3\cdot10^6)，因此输入本身已经有数百万个字符长。 任何重复扫描整个字符串、尝试多种基数或对生成的巨大数字执行整数分解的解决方案都是不合适的。 我们本质上希望对数字进行一次线性传递。 有用的事实是所有数字的总和最多为 (9\cdot3\cdot10^6=27\cdot10^6)，远低于 (10^9)。 这为我们提供了一个足够小的候选基数和除数。 

有几个小案例是盲目套用主体建设而失败的。 用于输入`1`，无论基数如何，表示的值始终为 (1)，因此不可能存在真除数，正确答案是`-1`。 用于输入`4`，数字和为 (4)，但选择和作为除数会得到 (X=D=4)，这不是真除数。 正确答案可以是`10 2`。 用于输入`10`，数字和为(1)，因此基于数字和的构造不能使用(X=1)。 然而，底数 (10) 给出 (D=10)，并且 (X=2) 有效。 这些情况解释了为什么最终算法将长度为 1 的字符串分开以及数字和为 1 的情况。 

## 方法

 直接方法会尝试基数 (B)，构造相应的数字 (D)，然后搜索除数 (X)。 即使仅在所有 (10^9) 个可能的碱基中进行选择，也至少给出了 (10^9) 个候选碱基。 从长度为 (n) 的字符串计算一个基数需要处理其数字，因此仅检查每个可能的基数至少需要 (10^9n) 个数字运算。 在进行任何分解之前，最大长度至少是 (3\cdot10^{15}) 次运算。 因式分解 (D) 更糟糕，因为 (D) 可能有数百万位小数。 

蛮力之所以有效，是因为测试候选基数和除数很简单，但它会失败，因为可能的基数空间很大，并且表示的数字也很大。 关键的观察是我们根本不需要明确地知道（D）。 

对于以 (B) 为基数的数字，以 (B-1) 为模进行减少会用 (1) 替换 (B) 的所有幂，因为 (B\equiv1\pmod{B-1})。 因此，如果数字是 (a_0,a_1,\ldots,a_{n-1})，那么

 [
 D=\sum a_iB^i\equiv\sum a_i\pmod{B-1}。 
]

 设数字和为(S)。 如果我们选择

 [
 B=S+1，
 ]

 那么 (B-1=S)，所以 (D\equiv S\equiv0\pmod S)。 因此 (X=S) 自动成为 (D) 的除数。 

这是中心建设。 由于 (S) 至少是每个单独的数字，因此 (B=S+1) 是有效基数。 由于 (S\le27\cdot10^6)，(B) 和 (X) 都明显低于 (10^9)。 

对于长度至少为 2 且 (S\ge2) 的字符串，(X=S) 也严格小于 (D)。 前导数字至少为 1，因此 (D\ge B=S+1>S=X)。 

唯一剩下的至少有两位数的情况是（S=1）。 由于第一个数字非零，因此该字符串必须是`100...0`。 选择 (B=10) 得到 (D=10^{n-1})，并且 (X=2) 是一个真除数。 最后，一位数字字符串准确地表示该数字，与基数无关。 只有当数字本身是合数时，这样的数字才有真约数，其中允许的数字意味着（4,6,8,9）。

 ## 算法演练

 1. 读取数字串并计算其长度和数字和（S）。 主体建设只需要总和，因此没有理由建造潜在的巨大数字（D）。 
2. 如果字符串只有一位数字，则单独处理。 无论基数如何，一位数表示的值始终等于该数字。 如果数字是(4,6,)或(8)，则选择(B=10)和(X=2)。 如果数字是（9），则选择（B=10）和（X=3）。 对于 (1,2,3,5,7)，该数字是质数，因此打印 (-1)。 
3. 如果字符串至少有两位数字且（S=1），则该字符串必然是`100...0`。 选择 (B=10) 和 (X=2)。 表示的值为(10^{n-1})，可以被(2)整除并且大于(2)。 
4. 否则 (n\ge2) 和 (S\ge2)。 设置 (X=S) 和 (B=S+1)。 基数是有效的，因为每个数字最多是 (S)，因此严格小于 (B)。 
5. 输出 (B) 和 (X)。 由于 (S\le27\cdot10^6)，两个值都满足 (10^9) 限制。 另外，(D>X)，因为(D\ge B=S+1)。 

### 为什么它有效

 主要构造背后的不变量是 (B\equiv1\pmod{B-1})。 对于 (B=S+1)，这变为 (B\equiv1\pmod S)。 因此，每个位置幂 (B^k) 都与 (1) 模 (S) 一致，因此整个表示的数字满足 (D\equiv S\equiv0\pmod S)。 因此 (X=S) 总是整除 (D)。 

该结构也满足所有限制。 数字和最多为 (27\cdot10^6)，因此 (B=S+1\le27,000,001) 和 (X=S\le27,000,000)。 因为 (S) 至少是最大数字，所以基数 (B) 中的每个数字都是有效的。 对于长度至少为 2 的字符串，(D\ge B>X)，因此除数是合适的。 特殊情况恰好涵盖了 (S) 不能作为有效真除数的情况。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve(s: str) -> str:
    n = len(s)
    digit_sum = sum(ord(c) - 48 for c in s)

    if n == 1:
        d = ord(s[0]) - 48

        if d in (4, 6, 8):
            return "10 2"
        if d == 9:
            return "10 3"
        return "-1"

    if digit_sum == 1:
        return "10 2"

    return f"{digit_sum + 1} {digit_sum}"

s = input().strip()
print(solve(s))
```第一遍计算数字和，而不将整个字符串转换为整数。 将最多 300 万位数字的字符串转换为整数是不必要的，并且在许多 Python 环境中，还会受到额外的转换限制。 

一位数分支是分开的，因为当只有一位数时，位置基数不起作用。 例如，`4`在每个有效基中都表示 (4)，因此我们实际上必须问 (4) 本身是否有真除数。 

对于数字和为 1 的多位字符串，第一位数字必须为 1，其他数字必须为零。 固定结构 (B=10,X=2) 之所以有效，是因为所表示的数字是 10 的正幂。 

在总支部，`digit_sum + 1`是基础并且`digit_sum`是除数。 该代码从不计算 (D)，这是主要的实现优势。 因此，无论输入长度如何，Python 整数仅用于以 (27\cdot10^6+1) 为界的微小值。 

Python 中不存在溢出问题，即使在具有固定宽度整数的语言中，构造的 (B) 和 (X) 也很容易在 32 位有符号整数范围内。 字符串被扫描一次，因此该实现还避免了任何隐藏的二次行为。

 ## 边缘情况

 用于输入`1`，算法立即进入一位数分支。 它的值在每个可能的基数中都是 (1)，因此不存在 (X>1) 且 (X<D) 的情况。 输出正确`-1`。 

用于输入`4`，一位数分支将 (4) 识别为复合并选择 (X=2)。 底数 (10) 有效，因为数字 (4) 小于 (10)，表示的值仍为 (4)。 因此`10 2`满足 (2<4) 和 (2\mid4)。 

用于输入`9`，算法使用 (X=3) 而不是 (2)，因为 (3\mid9)。 输出`10 3`表示(D=9)，所以除数是正确的。 

用于输入`10`，数字和为 (1)，使得主要构造变得不可能，因为它需要 (X=1)。 特殊分支选择(B=10)，给出(D=10)，并且(X=2)是真因数。 相同的推理适用于表单的每个输入`100...0`至少有两位数。 

对于诸如这样的输入`2222`，数字和为(8)，因此算法选择(B=9)和(X=8)。 所代表的值为

 [
 2\cdot9^3+2\cdot9^2+2\cdot9+2=1622,
 ]

 (1622) 可被 (8) 整除。 同余论证给出了这一点，而没有构造（D）。 

对于最大尺寸输入，包括`1`后面跟着 (2,999,999) 个零，数字和仍然是 (1)。 因此，该算法不会尝试处理巨大的表示数字。 它返回`10 2`紧接在线性数字求和之后，表示的值为 (10^{2,999,999})，它肯定能被 (2) 整除并且大于 (2)。
