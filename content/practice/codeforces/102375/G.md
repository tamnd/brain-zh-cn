 ## 解决方案
 ## 问题理解

 我们得到了一个十进制数字字符串，但这些数字不一定要以 10 为基数进行解释。我们可以选择一个基数 (B)，只要字符串中的每个数字在该基数中都是有效的。 如果数字为(a_{N-1}\ldots a_1a_0)，则表示的数字为

 [
 D=a_{N-1}B^{N-1}+a_{N-2}B^{N-2}+\cdots+a_1B+a_0。 
]

 我们需要选择 (B) 和 (D) 的真因数 (X)，两个值都在 2 到 (10^9) 之间。 数字 (D) 本身可能非常大，因为输入最多包含 (3\cdot10^6) 位数字，因此不可能将其构造为整数。 

决定性的约束是输入的长度。 对于三百万位数字，检查许多可能的基数或除数的算法无法工作。 我们基本上需要对字符串进行一次或几次线性扫描。 (B) 和 (X) 上的界限 (10^9) 对于从数字和导出的值来说足够大，因为最大可能的数字和仅为 (9\cdot3\cdot10^6=27\cdot10^6)。 

有两种小情况，粗心的解决方案可能会处理不当。 用于输入`1`，无论基数如何，表示的值始终为 1，因此没有真除数，答案为`-1`。 用于输入`4`，该值始终为 4，但它确实有正确的除数 2，因此答案存在，例如`10 2`。 假设每个一位数字输入都是不可能的解决方案将在这里失败。 

另一种特殊情况是数字和为1的多位字符串，例如`10`或者`1000`。 下面的主结构会尝试使用(X=1)，这是禁止的。 为了`10`，选择 (B=4) 给出 (D=4)，因此 (X=2) 有效。 相同的构造适用于该形式的每个字符串`100...0`。 

## 方法

 直接的方法是逐一尝试基地。 对于每个候选基数 (B)，我们将评估数字字符串表示的多项式，然后搜索除数。 即使忽略除数搜索，也可能有 (10^9) 个可能的基数。 评估每个基数的长度 (N) 字符串的成本为 (O(N))，给出大约 (10^9N) 位数字运算，在最大输入大小下达到大约 (3\cdot10^{15}) 次运算。 尝试每一对 ((B,X)) 的情况更糟，最多可达 (10^{18}) 对。 

有用的观察结果是，多项式的值变得非常简单，以与基数相关的数为模。 假设所有数字之和为(S)，则选择

 [
 X=S,\qquad B=S+1。 
]

 然后(B\equiv1\pmod S)。 因此 (B) 的每一次幂也都等于 1 模 (S)，所以

 [
 D\equiv a_{N-1}+a_{N-2}+\cdots+a_0=S\equiv0\pmod S。 
]

 因此（S）自动除以（D）。 我们将问题从求大数的除数转化为简单地计算数字和。 

对于 (S\ge2) 和 (N\ge2)，该构造始终有效。 由于 (S) 至少是每个数字，因此 (B=S+1) 严格大于每个数字并且是合法的基数。 另外 (S\le27\cdot10^6)，因此 (B) 和 (X) 都安全地低于 (10^9)。 最后，因为至少有两位数字，并且（B）是有效基数，（D>B>S），所以（X=S）是真除数而不是整数。 

(N\ge2) 唯一剩下的情况是 (S=1)。 由于第一位数字非零，这意味着输入恰好是`100...0`。 选择(B=4)使得表示的数字(D=4^{N-1})。 对于 (N\ge2)，这至少为 4 并且可被 (X=2) 整除。 

对于一位数输入，更改基数根本不会更改值。 该值就是那个数字。 数字1到9中的合数是4、6、8和9。它们的真约数分别是2、2、2和3。 剩下的数字没有真因数，所以答案是`-1`。

 ## 算法演练

 1. 读取数字串并一次性计算其数字和（S）。 我们只需要总和，而不需要字符串表示的巨大数字。 
2. 如果字符串有一位数字，则直接检查该数字。 对于 4、6 和 8 输出，基数 10 和除数 2。 对于 9 输出，基数 10 和除数 3。 对于 1、2、3、5 和 7 输出`-1`，因为这些值没有真除数。 
3. 如果至少有两位数并且（S=1），则输出（B=4）和（X=2）。 输入必须是`100...0`，所以它以 4 为底的值为 (4^{N-1})，它至少为 4 并且能被 2 整除。 
4. 如果和(S\ge2)至少有两位数，则设置(X=S)和(B=S+1)。 该选择的设计使得 (B\equiv1\pmod X) 使得 (B) 的每个幂都等于 1 模 (X)。 
5. 由于每个数字最多为（S），因此基数（B=S+1）有效。 最大可能的和是 (27\cdot10^6)，因此 (B) 和 (X) 都低于 (10^9)。 
6. 所代表的数字满足

 [
 D\equiv\sum a_i=S\equiv0\pmod S,
 ]

 (D>S)，因为该字符串至少有两位数字。 因此该对是有效的。 

### 为什么它有效

 中心不变量是，当 (B=S+1) 时，每个幂 (B^k) 都与 1 模 (S) 全等。 因此，整个基数 (B) 会以其模数 (S) 折叠为其数字和。 选择等于该数字和的除数会使余数为零。 特殊情况（S=1）单独处理，因为 1 不能用作除数，而一位数输入单独处理，因为更改基数不能更改其数值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve(s: str) -> str:
    n = len(s)
    digits = [ord(c) - 48 for c in s]
    total = sum(digits)

    if n == 1:
        d = digits[0]

        if d == 4 or d == 6 or d == 8:
            return "10 2"
        if d == 9:
            return "10 3"

        return "-1"

    if total == 1:
        return "4 2"

    x = total
    b = total + 1
    return f"{b} {x}"

s = input().strip()
print(solve(s))
```第一行`solve`计算数字和而不将输入转换为整数。 Python 整数可以任意大，但构造一个三百万位的整数仍然是不必要且昂贵的。 

对于一位数字输入，代码明确处理四个复合数字。 基数 10 对于从 1 到 9 的每个输入数字都有效，因此无需搜索基数。 

对于数字和为 1 的多位输入，唯一可能的形式是`100...0`。 这对`4 2`即使对于最短的此类字符串也有效，`10`，因为它的以 4 为底的值恰好是 4。 

对于所有剩余的输入，`total`至少为 2。代码输出`total + 1`作为基础和`total`作为除数。 Python中不存在溢出问题，并且最大值`total`只有2700万。 

对每个数字 (d_i) 的基数是否有效的检查直接来自 (S\ge d_i)，给出 (B=S+1>d_i)。 不会将整个字符串转换为表示的数字。

## 边缘情况

 输入`1`是可能的最小字符串。 每个基数的表示值为 1，因此不存在真除数。 一位数分支检测到该值不是 4、6、8 或 9 之一并返回`-1`。 

输入`4`演示了相反的一位数情况。 无论基数如何，该值都保持为 4，并且 2 是真除数。 算法输出`10 2`，其中基数 10 有效，因为唯一的数字是 4。 

输入`10`有两位数，但数字和为 1。使用通式会产生 (X=1)，这是禁止的。 特殊分支反而选择 (B=4) 和 (X=2)。 表示的值为 (1\cdot4+0=4)，因此 (2) 是有效的真除数。 

对于完全由 9 组成的最大长度输入，数字和为 (27,000,000)。 该算法选择 (X=27,000,000) 和 (B=27,000,001)。 两者都在(10^9)以下，并且每一位数字都小于底数。 由于 (B\equiv1\pmod X)，无论其大小如何，所表示的数字都可以被 (X) 整除。 

边界条件 (D>X) 也值得特别注意。 对于一般情况下的每个多位输入，前导数字为正，因此表示的值至少包含 (B) 的一个正倍数。 因此 (D\ge B)，并且因为 (B=S+1)，我们得到 (D>S=X)。 除数永远不会意外地等于所表示的整数。
