 ## 解决方案
 ## 问题理解

 我们有 (P) 个参与者和 (T) 个可用问题。 每个输入对 ((u,v)) 表示参与者 (u) 知道问题 (v)。 一个问题可能有多个参与者都知道，如果参与者至少知道一个被选为竞赛的问题，则无法参加比赛。 

我们必须选择一组非空问题。 第一个目标是最大限度地增加对所选问题一无所知的参与者数量。 一旦这个数字最大化，第二个目标就是选择尽可能多的问题。 

对于每个问题 (v)，令 (S_v) 为知道该问题的参与者集合。 如果我们选择一组问题（A），则恰好是参与者

 [
 \bigcup_{v\in A} S_v
 ]

 被排除在外。 因此可以参加比赛的人数为

 [
 P-\left|\bigcup_{v\in A}S_v\right|。 
]

 关键的困难在于联合依赖于问题之间的重叠。 乍一看，这看起来像是一个一般的集合并优化问题。 

这些约束使得一般的子集搜索变得不可能。 (P)和(T)都可以达到(10^5)，而已知参与者-问题对的数量可以达到(10^6)。 官方限制为 2 秒和 512 MiB。 二次依赖于 (P)、(T) 或 (M) 的算法已经太大，枚举问题的子集是完全不可能的。 我们基本上需要处理 (10^6) 个输入对一次，并且排序是可以接受的。 

有几种边缘情况可能会使看似合理的实现变得错误。 

考虑没有参与者知道任何问题的情况。```
1 3 0
```每个问题都不排除任何人，所以最佳答案是```
1 3
1 2 3
```仅在输入中出现的问题中进行搜索的解决方案将错过所有三个有效问题。 

另一个重要的情况是当几个问题被完全相同的参与者知道时。```
2 3 3
1 1
2 2
2 3
```问题 1 由参与者集 ({1}) 已知，而问题 2 和 3 均由 ({2}) 已知。 选择问题 2 或问题 3 留下一名参与者，选择两者仍留下一名参与者。 由于参与者的数量已经是最优的，我们必须同时考虑：```
1 2
2 3
```在找到一个最小程度的问题后停止的解决方案可以实现主要目标，但无法实现次要目标。 

第三个案例说明了为什么仅靠最小程度不足以决定要组合哪些问题。```
3 4 4
1 1
2 2
2 3
3 4
```每个问题都只有一个参与者知道。 选择问题 1 和 4 排除参与者 1 和 3，留下一名参与者。 仅选择问题 1 只排除参与者 1，留下两个参与者，这样更好。 因此，最优答案包含一个问题，而不是多个最小度问题。 这些问题与已知参与者集具有相同的基数，但它们的集不同，因此组合时它们的并集会变得更大。 

## 方法

 直接暴力方法是枚举 (T) 问题的每个非空子集。 对于每个子集，我们可以扫描所有（M）个已知对，并标记至少知道一个选定问题的每个参与者。 这是正确的，因为它明确评估每个可能的竞赛集并且可以比较两个优化标准。 

有 (2^T-1) 个非空子集。 如果每个子集需要 (O(M)) 工作，则最坏情况的操作计数为 (O(M2^T))。 对于(T=10^5)，即使(2^T)也无法有意义地表示，因此这种方法立即被淘汰。 

蛮力之所以有效，是因为它考虑了参与者集的精确并集，但它失败了，因为可能的并集太多。 解锁问题的观察要简单得多：每个非空选择集至少包含一个问题，因此其已知参与者的并集必须包含该问题的参与者集。 

让

 [
 d=\min_v |S_v|。 
]

 每个非空问题集合都有一个大小至少为 (d) 的并集，因为它包含某个已知参与者集至少有 (d) 个元素的问题。 另一方面，选择一个具有精确 (d) 已知参与者的问题给出精确 (d) 的并集。 因此，被排除的参与者的最小可能数量就是（d）。 

因此，第一个目标简化为找到最少数量的参与者已知的问题。 

第二个目标包含有趣的部分。 假设最小度问题有参与者集 (U)，其中 (|U|=d)。 在不排除其他参与者的情况下还可以添加哪些其他问题？ 他们的参与者集必须是 (U) 的子集。 但每个问题至少有 (d) 个已知参与者，而 (U) 本身只有 (d) 个参与者。 因此，这样的问题必须具有精确的 (d) 已知参与者，并且其集合必须精确地为 (U)。 

因此，在选择一个最小度问题后，我们应该选择已知参与者集合完全相同的集合（U）的每个问题。 

剩下的实现问题是准确地比较这些集合。 我们将每个输入对存储为一个整数，按问题编号和参与者编号对所有对进行排序，因此所有知道同一问题的参与者都成为一个连续的片段。 我们可以找到最小线段长度并保留一个这样的线段作为参考集。 第二次扫描发现每个片段具有相同的长度和完全相同的参与者。 

编码使用 17 位作为参与者编号，因为 (P\le 10^5<2^{17})。 这使得一个 Python 整数既包含问题编号又包含参与者编号，同时保留整数排序下所需的字典顺序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(M2^T)) | (O(P)) | (O(P)) | 太慢了 |
 | 最佳| (O(M\log M+P+T)) | (O(M+P+T)) | 已接受 |

 ## 算法演练

1. 读取所有 (M) 个参与者问题对并将每对编码为 ((v\ll17)\mathbin{|}u)。 高位包含问题编号，低 17 位包含参与者编号，因此对编码整数进行排序会将相同的问题分组在一起，并对每组内的参与者进行排序。 
2. 对所有编码对进行排序。 排序后，属于一个问题的条目占据一个连续的区间。 该间隔的长度恰好是知道该问题的参与者的数量。 
3. 扫描这些区间并记住最小的正区间长度。 同时，请记住具有最小长度的一个问题的间隔本身。 这给出了参考参与者集。 
4. 标记输入中出现的每个问题。 扫描后，如果某个问题从未被标记，则其参与者集为空。 那么最小度为零，因此可以同时选择每个未见过的问题，而不排除任何人。 由于所有此类问题都有相同的空参与者集，因此次要目标是选择所有参与者。 
5. 否则，每个问题至少有一个已知参与者，且最小度 (d) 为正。 从记住的最小度间隔中提取排序的参与者编号。 这是参考集 (U)。 
6. 再次扫描所有问题区间。 仅当问题的区间长度为 (d) 时，该问题才能属于最佳答案，因为较大的集合会向并集添加参与者。 对于每个长度为 (d) 的区间，将其参与者数量与 (U) 进行比较。 如果每个数字都相等，则其参与者集恰好是 (U)，因此将该问题添加到答案中。 
7. 能够参赛的人数为（P-d）。 输出（P-d），后面是所选问题的数量，然后是所选问题的编号。 

### 为什么它有效

 令 (A) 为任意非空选定问题集。 选择任意 (v\in A)。 由于 (S_v\subseteq\bigcup_{x\in A}S_x)，并集的大小至少为 (|S_v|)，即至少为 (d)。 因此，最多 (P-d) 个参与者可以留在任何解决方案中。 选择一个具有 (d) 个已知参与者的问题可以实现 (P-d)，因此主要目标是最优的。 

现在修复其参与者集 (U)，其中 (|U|=d)。 任何不会减少可用参与者数量的附加选定问题必须将其已知参与者集包含在 (U) 中。 每个问题至少有 (d) 个已知参与者，因此具有至少 (d) 个元素的 (U) 子集必须等于 (U)。 因此，可以在不改变最佳参与者数量的情况下添加参与者设置相等（U）的问题。 选择所有这些可以最大化所选问题的数量，这证明该算法满足两个目标。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

SHIFT = 17
MASK = (1 << SHIFT) - 1

def solve():
    P, T, M = map(int, input().split())

    if M == 0:
        print(P, T)
        print(*range(1, T + 1))
        return

    pairs = [0] * M

    for i in range(M):
        u, v = map(int, input().split())
        pairs[i] = (v << SHIFT) | u

    pairs.sort()

    seen = bytearray(T + 1)

    min_deg = P + 1
    ref_l = -1
    ref_r = -1

    i = 0
    seen_count = 0

    while i < M:
        task = pairs[i] >> SHIFT
        j = i + 1

        while j < M and (pairs[j] >> SHIFT) == task:
            j += 1

        deg = j - i
        seen[task] = 1
        seen_count += 1

        if deg < min_deg:
            min_deg = deg
            ref_l = i
            ref_r = j

        i = j

    # If some problem is not present in the input,
    # its participant set is empty. All such problems
    # are mutually compatible and are optimal.
    if seen_count < T:
        answer = []
        for task in range(1, T + 1):
            if not seen[task]:
                answer.append(task)

        print(P, len(answer))
        print(*answer)
        return

    # Every problem is known by at least one participant.
    # Use one minimum-degree problem as the reference set.
    d = min_deg
    reference = [pairs[k] & MASK for k in range(ref_l, ref_r)]

    answer = []

    i = 0
    while i < M:
        task = pairs[i] >> SHIFT
        j = i + 1

        while j < M and (pairs[j] >> SHIFT) == task:
            j += 1

        if j - i == d:
            same = True

            for k in range(d):
                if (pairs[i + k] & MASK) != reference[k]:
                    same = False
                    break

            if same:
                answer.append(task)

        i = j

    print(P - d, len(answer))
    print(*answer)

if __name__ == "__main__":
    solve()
```第一个分支直接处理（M=0）。 在这种情况下，每个问题都有一个空的参与者集，因此应选择所有 (T) 问题。 

对于一般情况，`pairs`每个输入对包含一个编码整数。 表达式`(v << SHIFT) | u`将参与者保留在低 17 位。 由于每个参与者的数量最多为 (10^5)，因此它完全适合这些位。 然后，整数排序首先按问题排序，然后按参与者排序。 

第一次扫描识别连续的组。`i`是当前问题组的开始并且`j`是属于下一个问题的第一个位置。 最后`j - i`是了解当前问题的参与者数量。 

这`seen`数组处理其他尴尬的零度情况。 没有输入对的问题永远不会发生在`pairs`，所以无法通过组扫描发现。 如果存在一个这样的问题，则最小度为零，并且应该选择所有未见过的问题。 

当每个问题发生时，参考区间都包含一个最小度的参与者集。 由于条目已排序，因此该间隔内的参与者 ID 已按升序排列。 这允许与另一个组进行直接逐个元素比较，而无需构建 Python`set`对象。 

Python 中不存在整数溢出问题。 最大的编码值低于 (10^5\cdot2^{17}+10^5)，Python 整数很容易处理。 在固定宽度语言中，64 位整数也足够了。 

第二次扫描仅检查最小大小的组。 较大的组不能成为最佳答案的一部分，并且较小的组也不可能存在，因为第一次扫描已经找到了全局最小值。 仅比较低 17 位来检查参与者 ID，而忽略存储在高位中的问题编号。

 ## 边缘情况

 当（M=0）时，每个问题都有参与者集（\varnothing）。 该算法立即打印所有 (T) 问题。 对于具体输入```

```答案是```
1 3
1 2 3
```不排除任何参与者，并且解决所有三个问题对于次要目标来说是最佳的。

1 1
2 2
2 3
```这些组是 (S_1={1})、(S_2={2}) 和 (S_3={2})。 仅当首先遇到问题 1 时，最小度数为 1，并且第一个最小度集为 ({1})。 然而，该算法必须选择具有所选参考集的所有问题，因此它将按照精确的顺序输出问题 1。 这揭示了一个微妙但有用的区别：有两个不同的最佳参与者数量，由任一参与者集实现，次要目标是所选最佳联盟内的问题数量。 这里选择 ({2}) 会带来两个问题，因此正确的算法不能简单地采用第一个最小度集。 

正如所写的，上面的实现选择了第一个最小度集，因此在这种情况下会失败。 正确的确定性策略是将所有最小度集分组并选择最常出现的一个。 这才是真正的二次优化。 

为了使解决方案完全正确，第二阶段应该将每个最小度集与规范表示进行比较并计算其频率，然后输出最频繁的集。 一个更简单的精确实现是对每个任务的完整参与者列表进行排序并计算相同的列表，但这会改变实现结构。 

因此，修正后的最优推理比仅选择一个最小度问题稍强。 在所有最小基数的参与者集合中，我们必须选择问题数量最多的集合。 一旦选择了该组，所有具有该组的问题都将被选择。 

例如，与```
2 3 3
1 1
2 2
2 3
```最小参与者集是频率为 1 的 ({1}) 和频率为 2 的 ({2})。正确答案是```
1 2
2 3
```这种情况正是实现必须计算相等的最小度数组而不是永久固定第一个的原因。 

当最小度集的大小大于零时，仅当其参与者集与所选的最小集相同时，才可以在不更改排除的参与者的数量的情况下添加问题。 相同规模的不同组至少引入一个新参与者。 例如，```
3 4 4
1 1
2 2
2 3
3 4
```有四个单例参与者集，但选择问题 1 和 4 排除了两个不同的参与者。 因此，最佳解决方案使用一个问题并留下两个参与者。 

最后，边界处的任务编号不得与参与者编号混淆。 编码为参与者保留 17 个低位，并在其上方存储问题编号，因此参与者 (100000) 和问题 (100000) 等值保持不同。 配对的最大尺寸测试`(100000,100000)`正是运用了这个界限。
