 ## 解决方案
 ## 问题理解

 我们有一个具有 (N) 个顶点的正多边形，并且我们想要保留其中一些顶点，以便保留的顶点本身形成正多边形。 目标是最小化保留顶点的数量。 

原始多边形的顶点围绕其圆周等距分布。 如果我们选择每个第 (t) 个顶点，则所选顶点的间距也相等，并且我们会得到一个具有 (N/t) 个顶点的正多边形，前提是 (t) 除 (N)。 同样，较小正多边形中的顶点数 (k) 必须是 (N) 的约数。 

有一个重要的限制：多边形必须至少具有三个顶点。 所以答案是 (N) 的最小除数，至少为 (3)。 

(N)的值可以达到(10^{12})。 这就排除了检查线性数量候选的算法，因为 (10^{12}) 次迭代远远超出了竞争性编程解决方案所能承受的范围。 另一方面，(\sqrt{10^{12}}=10^6)，因此仅检查除数到平方根的试除法算法很容易实用。 

有两种边缘情况可以欺骗简单的平方根搜索。 首先，像 (N=5) 这样的质数根本没有真约数，所以答案是 (5)，而不是某个不存在的较小多边形。 其次，偶数（例如（N=14））的除数为（2），但不允许是 2 边形。 下一个可能的除数是 (7)，它大于 (\sqrt{14})。 仅检查 (3,4,\ldots,\lfloor\sqrt N\rfloor) 的搜索将错误地返回 (14)。 因此，必须明确处理除数 (2) 的特殊作用。 

对于 (N=4)，唯一的约数是 (1,2,4)，所以答案是 (4)。 这是处理因子 (2) 的另一个边界情况，因为 (N/2=2) 不是有效的多边形。 

## 方法

 直接的方法是尝试从（3）到（N）中选择的所有可能数量的顶点（k），并检查（k）是否整除（N）。 找到的第一个除数就是答案，因为每个有效的正则子多边形完全对应于 (N) 的除数。 这是正确的，但是对于 (N=10^{12}) 它可以执行几乎 (10^{12}) 次整除性检查，这太慢了。 

除数的结构为我们提供了所需的约简。 如果整数 (N) 具有除 (1) 和 (N) 之外的除数 (d)，则它还具有补除数 (N/d)。 这两者中至少有一个最多是 (\sqrt N)。 这意味着对于奇数 (N)，如果存在有效的真除数，则 (3) 和 (\sqrt N) 之间必须存在某个除数。 我们可以直接搜索那个小范围。 

唯一的复杂因素是因子 (2)。 如果 (N) 是偶数，则 (2) 自动成为其最小素因数，但 (2) 不能作为答案。 它的补除数（N/2）可以是最小的有效除数，并且可以大于（\sqrt N）。 例如，(14=2\cdot7) 和 (7>\sqrt{14})。 因此，只要 (N/2) 至少为 (3)，我们就将其视为附加候选者。 

我们从 (3) 向上扫描除数。 找到的第一个除数自动成为最小的可能答案。 如果没有找到，那么奇数 (N) 一定是素数，所以答案是 (N)。 对于偶数 (N)，剩余候选者为 (N/2)，除非该候选者等于 (2)，如 (N=4) 时发生的情况。

 | 蛮力 | (O(N)) | (O(1)) | (O(1)) | 太慢了 |

 ## 算法演练

1. 阅读（N）。 我们需要 (N) 的最小除数，至少为 (3)。 
2. 如果(N=3)，则立即返回(3)。 不存在更小的有效多边形，这也避免了对平方根进行任何特殊处理。 
3. 如果 (N) 是偶数，则在 (N/2\ge3) 时将候选答案设置为 (N/2)。 这可以处理诸如 (14=2\cdot7) 的情况，其中最小有效除数大于 (\sqrt N)。 对于(N=4)，(N/2=2)无效，因此候选仍然是(N)。 
4. 尝试从 (3) 到 (\lfloor\sqrt N\rfloor) 的每个整数 (d)。 如果 (N\bmod d=0)，则 (d) 是有效的多边形大小。 由于这些值是按升序测试的，因此第一个这样的 (d) 是最小的可能答案，因此立即返回它。 
5. 如果搜索完成后未找到除数，则返回步骤 3 中的候选项，如果没有有效候选项，则返回 (N)。 对于奇数 (N)，这意味着 (N) 是素数。 对于偶数 (N)，这意味着 (N/2) 是唯一可能大于 (2) 的真因数，可以作为答案。 

为什么它有效：每个可能的正则子多边形都有许多顶点划分（N）。 在所有有效除数中，该算法显式地考虑唯一可以隐藏在 (\sqrt N) 之上的除数，即 (2) 除 (N) 时的 (N/2)，而其他所有可能的最小除数必须至多为 (\sqrt N)。 因此，无论何时存在，升序试除法都会找到最小的有效除数，而回退则处理剩余的素数或 (2) 倍素数情况。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    # N itself is always a valid answer.
    ans = n

    # If 2 divides N, then N / 2 is the only possible
    # complementary divisor that can remain above sqrt(N).
    if n % 2 == 0 and n // 2 >= 3:
        ans = n // 2

    d = 3
    while d * d <= n:
        if n % d == 0:
            ans = d
            break
        d += 1

    print(ans)

solve()
```初始值`ans = n`表示原始多边形本身是最小有效选择的情况。 (N) 的每个除数都是可能的顶点数，并且 (N) 始终是有效的，因为 (N\ge3)。 

这`n % 2 == 0`分支处理特殊除数 (2)。 我们不能返回 (2)，因为正多边形至少需要三个顶点，但只要补除数 (n/2) 至少为 (3)，它就有效。 这就是为什么 (N=14) 产生 (7)，即使 (7) 大于 (\sqrt{14})。 

循环从 (3) 开始，而不是 (2)，因为 (2) 永远不是有效答案。 它继续，同时`d * d <= n`，它是 (d\le\sqrt N) 的整数形式，避免了浮点计算。 Python 整数具有任意精度，因此`d * d`不能溢出。 

一旦找到除数，循环就会停止。 自从`d`从 (3) 开始增加，该除数是遇到的最小有效除数，因此也是答案。 

## 工作示例

 对于（N=5），多边形是质数，因此没有真因数可以表示较小正多边形的顶点数。

 | --- | --- | --- | --- | --- |

 循环停止是因为 (3^2>5)。 没有找到至少 (3) 的除数，因此原始五边形是由其顶点形成的最小可能的正多边形。 这演示了素数情况。 

对于 (N=21)，与答案相关的除数是 (3) 和 (7)。 该算法立即找到 (3)。 

| (N)| （答）最初 | (d) | (N\bmod d) | 行动|
 | --- | --- | --- | --- | --- |
 | 21 | 21 21 | 21 3 | 0 | 返回 3 |

 选择原始 21 边形的每七个顶点会留下三个等距的顶点，因此三角形是可能的。 由于不允许有少于三个顶点的多边形，因此 (3) 是最佳的。 这证实了升序排列的第一个除数正是所需的答案。

 ## 边缘情况

 对于 (N=5)，算法开始于`ans = 5`并且不会创建偶数候选。 该循环需要从 (3) 开始测试除数，但是 (3^2>5)，因此它不执行有用的除数测试并返回 (5)。 假设每个多边形都有一个较小的正则子多边形的粗心实现可能会错误地搜索不存在的除数。 

对于 (N=14)，算法首先设置`ans = 7`，因为 (14/2=7)。 循环测试 (d=3)，但是 (14\bmod3\ne0)，然后停止，因为 (4^2>14)。 返回存储的答案（7）。 这是一个关键案例，说明了当因子 (2) 被禁止作为答案时，为什么仅检查 (\sqrt N) 是不够的。 

对于（N=4），`n // 2`等于(2)，所以偶数分支故意不更新`ans`。 循环没有满足(d^2\le4)的(d\ge3)，算法返回(4)。 无条件返回 (N/2) 将产生 (2)，它不描述多边形。 

对于(N=49)，循环达到(d=7)，并且(7^2=49)，所以边界条件`d * d <= n`包括这个除数。 从 (7\mid49) 开始，算法返回 (7)。 使用`d * d < n`相反，会跳过精确平方除数并错误地返回 (49)。 

对于(N=10^{12})，算法在找到(4)之前只需要少量的试除。 与线性算法可以检查的顶点数量相比，输入本身是巨大的，但其平方根仅为 (10^6)，这正是基于除数的约简使问题易于处理的原因。
