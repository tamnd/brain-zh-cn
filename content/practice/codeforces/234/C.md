 ## 解决方案
 ## 问题理解

 我们得到了一系列每日温度。 我们可以将任何温度更改为任何其他值，并且每个修改的位置都会花费一次更改。 

目标是使序列遵循非常特定的模式。 必须有一个分割位置，使得分割之前的每一天都具有严格的负温度，而分割之后的每一天都具有严格的正温度。 两个部分都必须非空。 最终序列中决不允许温度为零。 

我们需要必须修改的最少位置数。 

天数可以大到$10^5$。 这立即排除了任何检查每个可能的分割然后再次扫描整个数组的算法，因为这需要$O(n^2)$工作，大致$10^{10}$最坏情况下的操作。 我们需要一些线性或近线性的东西。 

棘手的部分是正确处理零。 分流两侧的温度为零均无效。 如果一天属于负数段，则必须更改零。 如果属于正段，也必须改零。 

另一个容易犯的错误是忘记两个段都必须至少包含一个元素。 例如：```
2
-5 -3
```答案是`1`， 不是`0`。 我们必须创建一个正后缀，因此至少有一个值必须更改。 

相似地：```
2
4 7
```答案是`1`，因为我们需要一个非空的负前缀。 

考虑：```
3
0 0 0
```每个位置都必须改变。 一个有效结果是`-1 -1 1`，所以答案是`3`。 任何将零视为已经可以接受的方法都会在这里失败。 

另一个微妙的例子是：```
4
-1 1 -2 1
```最好的分割是在第三个元素之后。 仅有的`-2`需要变得积极，所以答案是`1`。 

## 方法

 暴力解决方案会尝试所有可能的分割位置。 

假设分割是在位置之后$k$。 然后位置$1 \ldots k$必须为负数，并且位置$k+1 \ldots n$必须是积极的。 我们可以计算有多少元素违反了这些要求，并在所有拆分中取最小值。 

这是正确的，因为它明确地评估每个有效的最终结构。 问题是速度。 有$n-1$可能的分割，并且天真地检查一个分割需要扫描整个数组。 复杂度变为$O(n^2)$，这对于$n=10^5$。 

关键的观察是，分裂的成本仅取决于两种违规行为。 

对于负数前缀，如果元素严格为负数，则该元素已经正确。 否则就必须改变。 

对于正数后缀，如果元素严格为正数，则该元素已经正确。 否则就必须改变。 

这建议预处理前缀和后缀信息。 

让：`prefix[i]`= 第一个元素的数量`i`位置不为负。 

这些正是需要修改的位置，如果第一个`i`元素形成负段。 

同样，让：`suffix[i]`= 位置的元素数量`i`到`n`这些都不是积极的。 

这些正是需要修改的位置，如果位置`i...n`形成了积极的部分。 

然后在位置后进行分割`k`，成本变为：```
prefix[k] + suffix[k+1]
```现在可以在线性预处理后在恒定时间内评估每个分割。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取温度数组。 
2. 构建前缀数组，其中`prefix[i]`存储位置之间有多少个元素`1...i`并不严格是消极的。 

如果某个元素为零或正数，则对该计数有贡献，因为任一值都需要在负段内进行修改。 
3. 构建后缀数组，其中`suffix[i]`存储位置之间有多少个元素`i...n`并不严格是积极的。 

如果某个元素为零或负数，则对该计数有贡献，因为任一值都需要在正数段内进行修改。 
4. 迭代每个有效的分割位置`k`从`1`到`n-1`。 
5. 计算：```
cost = prefix[k] + suffix[k+1]
```第一项计算负前缀中所需的修改。 第二项计算正后缀中所需的修改。 
6. 保持所有拆分的成本最小。 
7. 输出找到的最小值。 

### 为什么它有效

 对于固定的分割位置，每个元素恰好属于一侧。 

如果某个元素位于负数前缀中，则当它不严格为负数时，需要对其进行精确修改。 前缀数组精确地计算这些违规情况。 

如果一个元素位于正数后缀中，则当它不是严格正数时，需要精确修改。 后缀数组精确计算这些违规行为。 

这两个段是不相交的，因此它们的修改计数直接相加。 由于每个有效的最终排列恰好对应一个分割位置，因此评估所有分割并取最小值会产生全局最优答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    t = list(map(int, input().split()))

    prefix = [0] * (n + 1)
    for i in range(1, n + 1):
        prefix[i] = prefix[i - 1] + (1 if t[i - 1] >= 0 else 0)

    suffix = [0] * (n + 2)
    for i in range(n, 0, -1):
        suffix[i] = suffix[i + 1] + (1 if t[i - 1] <= 0 else 0)

    ans = n
    for k in range(1, n):
        ans = min(ans, prefix[k] + suffix[k + 1])

    print(ans)

if __name__ == "__main__":
    solve()
```前缀结构直接遵循定义。 每个大于或等于零的值都会违反负数段，因此我们在以下情况下添加 1：`t[i-1] >= 0`。 

后缀结构是对称的。 每个小于或等于 0 的值都会违反正段，因此我们在以下情况下添加 1：`t[i-1] <= 0`。 

最常见的实施错误是错误地处理零。 零对双方来说都是无效的，因此它会根据其放置位置而对两种违规计数产生影响。 

另一个容易出现的差一错误出现在分割循环中。 分割必须使两个部分都非空，因此有效值为`1`通过`n-1`。 允许`0`或者`n`会创建一个空段并产生错误的答案。 

不存在整数溢出问题，因为所有计数最多为`n`。

 ## 边缘情况

 考虑：```
2
-5 -3
```前缀数组变为：```
0 0
```最后一个位置的后缀违规计数为：```
1
```在第一个元素之后只有一个有效的分割。 成本是：```
0 + 1 = 1
```一个温度必须变为正值。 算法正确输出`1`。 

现在考虑：```
2
4 7
```唯一有效的分割再次发生在第一个元素之后。 

第一个元素属于负数段并且是正数，因此它贡献了一个违规。 第二个要素已经是积极的。 

计算的成本是`1`，这是最优的。 

最后考虑：```
3
0 0 0
```无论属于哪一方，每一个零都会构成违规。 该算法对每个位置计算一次修改并返回`3`。 

这是完全正确的，因为每个温度必须要么严格为负，要么严格为正，并且没有一个可以保持为零。
