 ## 解决方案
 ## 问题理解

 我们得到三个长度相等的字符串。 将它们视为按列对齐的三行字符。 在每一列位置，我们只能执行一个操作：我们选择第三个字符串中的字符并将其与第一个字符串中的字符交换，或者将其与第二个字符串中的字符交换。 不允许其他交互，并且每个列都是独立处理的。 

在对每个位置执行一次交换后，目标是确定第一串和第二串是否可以变得相同。 

关键是每个位置都是孤立的。 在索引 i 处，我们只排列三元组`(a[i], b[i], c[i])`通过交换`c[i]`与另外两个之一。 我们永远不允许直接交换`a[i]`和`b[i]`。 

约束很小：每个字符串的长度最多为 100，并且最多有 100 个测试用例。 这立即排除了每个测试用例超出线性或二次的任何内容，但实际上该结构表明每个测试解决方案的 O(n) 是预期的。 

当本地选择在全球范围内发生冲突时，就会出现微妙的边缘情况。 一种幼稚的方法可能会尝试贪婪地匹配以下字符`a`和`b`不考虑掉期如何影响`c`，但由于操作是针对每个索引且独立的，因此这种全局推理是不必要的。 另一个常见的错误是假设我们可以跨索引自由地重新排列字符，这是错误的，因为交换永远不会在位置之间移动字符。 

## 方法

 强力解释将尝试所有方法来选择每个索引是否`c[i]`与交换`a[i]`或与`b[i]`。 每个位置有 2 个选择，所以`2^n`总配置。 对于每个配置，我们模拟所有交换并检查结果是否`a`等于`b`。 这是正确的，但呈指数增长。 即使 n = 100，这也是完全不可行的。 

关键的观察是我们实际上不需要模拟最终的字符串。 在交换后的每个位置，三个字符的集合保持不变，只是排列了顺序。 所以真正的问题是本地的：我们能否在每个位置分配值，以便最终`a[i]`等于最终`b[i]`？ 

在索引 i 处，我们从三元组开始`(a[i], b[i], c[i])`。 允许交换后，`c[i]`最终处于任一位置`a[i]`或者`b[i]`。 这意味着在每个索引处，我们选择哪两个字符成为最终的`(a[i], b[i])`对，而剩下的字符成为新的`c[i]`。 

所以问题简化为：对于每个索引，我们是否可以选择一个分配，使得`a[i] == b[i]`重新分配后？ 

这意味着我们必须确保对于每个索引，我们可以从三元组中选择一个可以作为两者的共享值的字符`a[i]`和`b[i]`。 但是，由于我们无法复制字符，只能交换，这是唯一的方法`a[i] == b[i]`是我们是否可以安排两个位置从该索引处的可用多重集中获取相同的字符。 

因此，对于每个位置，我们检查其中是否存在值`{a[i], b[i], c[i]}`可以同时放入`a[i]`和`b[i]`通过有效的互换。 这是可能的，除非结构强制产生矛盾，而这种矛盾只有在以下情况下才会发生：`a[i]`和`b[i]`以一种无法调和的方式固定`c[i]`作为帮手。 

由于每个指数都是独立的，我们只需要验证互换规则下每个头寸的可行性，而不需要构造一个明确的全局安排。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 对于每个索引 i，检查三元组`(a[i], b[i], c[i])`。 

目标是确定是否可以使位置 a[i] 和 b[i] 处的最终字符相等。 
2.如果`a[i] == b[i]`，那么这个位置已经是一致的，并且不需要交换来强制该索引处的相等。 我们继续。 
3.如果`a[i] != b[i]`，那么我们必须依赖`c[i]`来解决不匹配问题。 一次交换后使两个位置相等的唯一方法是`c[i]`可以交换到一侧，同时将冲突的角色推入`c[i]`，只有在以下情况下才有效地允许对齐`c[i]`以可用的方式匹配两个目标之一。 如果两者都不是`a[i]`也不`b[i]`可以通过交换作为共同解析值`c[i]`，那么这个索引完全阻止了构建。 
4. 如果每个指标都可行，则输出“YES”。 否则，我们输出“NO”。 

该实现简化为线性扫描，每个位置进行本地一致性检查。 

### 为什么它有效

 每个操作都严格限于单个索引，并且交换永远不会跨索引交互。 这将问题分解为每个位置的独立约束。 使最终字符串相同的唯一方法是确保每个位置都允许与交换规则一致的有效本地值分配。 由于没有任何操作在索引之间传播信息，因此满足所有局部约束既是必要的也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a = input().strip()
        b = input().strip()
        c = input().strip()
        
        ok = True
        
        for i in range(len(a)):
            if a[i] == b[i]:
                continue
            
            # We need to use c[i] to reconcile mismatch
            # If c[i] matches neither, we cannot fix this position
            if c[i] != a[i] and c[i] != b[i]:
                ok = False
                break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```该解决方案迭代每个测试用例并独立检查每个位置。 关键的实现细节是不匹配条件：当`a[i] != b[i]`，唯一可能的救援字符是`c[i]`，因为交换只允许移动`c[i]`到另外两个位置之一。 如果`c[i]`与两者无关，没有交换序列可以使双方相等。 

早期中断确保我们在发现不可能的位置后立即停止处理测试用例。

 ## 边缘情况

 一个重要的边缘情况是当`a == b`从一开始。 该算法立即正确输出 YES，因为每个索引都通过了相等性检查，而不需要任何帮助`c`。 

另一种情况是只有一些索引不匹配。 例如：```
a = "ab"
b = "ac"
c = "xx"
```在索引 1 处，`a == b`，所以是安全的。 在索引 2 处，发生不匹配并且`c[2]`与两者无关`a[2]`和`b[2]`，因此算法拒绝测试用例。 扫描提前停止，反映出单个不可能的位置使整个结构失效。 

第三种情况是当`c[i]`匹配其中之一`a[i]`或者`b[i]`。 例如：```
a = "ab"
b = "ba"
c = "aa"
```在索引 1 处，不匹配问题得到解决，因为`c[1]`比赛`a[1]`。 在索引 2 处，不匹配问题得到解决，因为`c[2]`比赛`b[2]`。 该算法接受，表明`c`充当灵活的中介，可以在本地吸收和重新分配角色。
