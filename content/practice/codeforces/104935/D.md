 ## 解决方案
 ## 问题理解

 我们一次构建一棵树的一个顶点。 最初只有顶点 1。每个查询都会添加一个新顶点并将其连接到某个现有顶点，因此该结构始终保持为有根生长的树。 

在每次添加之后（或仅在最后一次添加之后，取决于测试类型），我们被要求针对将顶点着色为红色或绿色的所有可能方式来评估以下优化问题。 

如果我们只看绿色顶点，它们会在树内形成一个连通组件的森林。 如果每个这样的绿色连通分量在原始树中最多有两个与其相邻的红色顶点，则该连通分量被称为有效。 换句话说，当我们检查一个绿色分量时，我们会计算有多少个红色邻居接触到它，如果这个数字是 0、1 或 2，则可以接受。 

对于固定树，我们可以选择任何顶点颜色。 在所有这些着色中，我们希望最大化有效绿色分量的数量，这个最大值由 f(t) 表示。 任务是随着树的生长维护或计算 f(t)。 

这些约束意味着每次查询后不可能进行简单的重新计算。 所有测试用例的顶点总数达到 4e5，因此任何每次更新重新访问树的大部分的解决方案都会立即失败。 这促使我们采用每节点 O(1) 或 O(log n) 更新策略，通常涉及贪婪不变量或可以增量维护的树 DP。 

有效性的定义出现了一个微妙的问题：它不仅取决于绿色分量的结构，还取决于有多少红色顶点接触它们。 这意味着着色的局部变化可能会影响全局的可行性，这使得直接贪婪着色不稳定，除非我们确定结构不变量。 

一个天真的错误是假设最大化绿色顶点或最大化局部组件是有效的。 例如，如果我们贪婪地将每个新节点着色为绿色，我们可能会认为每个孤立的绿色节点都贡献一个组件。 但是，如果一个节点最终与太多红色顶点相邻，则稍后的合并或分裂决策可以以非局部方式减少计数。 困难在于目标不是在节点上累加，而是在具有边界约束的组件上累加。 

## 方法

 强力策略是在每次更新后考虑树的每种可能的颜色，并计算有效绿色分量的数量。 即使忽略指数着色，我们也可以尝试对树的每个状态进行动态编程解决方案，但每次插入后从头开始重新计算 DP 每次查询的成本为 O(n)，在最坏的情况下导致总工作量为 O(n^2)。 节点总数为 4e5 个，这远远超出了可行的限制。 

关键的观察结果是“每个绿色分量最多有两个红色邻居”的约束非常严格。 每个绿色组件只能容忍有限数量的外部红色附件。 这表明只有高度顶点周围的局部结构才重要，因为每次我们附加一个新叶子时，它只能影响一个现有节点的邻域。 

如果我们以顶点 1 为树根，则每次插入都会添加一个新叶子，因此只会引入一条新边。 这强烈暗示可以仅使用有关新节点的父节点及其在进化树中的当前度数的信息来增量更新答案。 

更深入的见解是，最佳配置从来不需要绿色组件的复杂全局布置。 相反，每个顶点可以根据它贡献的“关键连接”数量进行分类，全局答案变成局部贡献的总和。 问题归结为跟踪有多少顶点可以充当绿色组件的“分隔符”，同时遵守红色邻接限制。

当新叶子附着到节点 u 时，只有 u 的度发生变化，并且只有 u 对最终最优结构的贡献可以改变。 这建议仅根据其当前程度维护每个节点的值，并相应地更新全局答案。 

这导致了一个简单的动态规则：每个节点根据其拥有的子节点数量贡献有限的数量，并且每次插入仅增加一个节点的状态，从而允许 O(1) 摊销更新。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（重新计算/完整 DP）| O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 基于增量度的不变量 | 总共 O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将树的根设在顶点 1 处，并随着树的生长保持每个节点的当前度数。 

1. 将除根之外的所有度数初始化为 0，根度开始时没有父级，但随着时间的推移会累积子级。 我们还维护一个初始化为 0 的全局答案。 
2. 对于作为附加到 u 的叶子添加的每个新顶点 v，我们递增 u 的度数。 树中唯一的结构变化是 u 增加了一个邻居。 
3.我们为每个节点u维护一个基于其当前度的贡献值。 关键的不变量是，只有度数至少为 2 的节点才能有助于增加最佳绿色分量的数量，因为叶子（度数为 1）不能充当分离绿色分量的分支结构。 
4. 当 u 的度数从 d 增加到 d+1 时，我们通过添加函数 delta(d) 来更新全局答案，该函数表示 u 由于其新子项而启用了多少个额外的“有用分离”。 
5. 仅当 u 达到特定阈值时，Delta 贡献才非零。 直观地说，一旦一个节点有足够的子节点，它就可以支持由红色邻接约束分隔的附加独立绿色组件。 前两个子项之外的每个额外子项都会使最佳计数增加固定数量。 
6. 处理完每个查询后，我们输出当前的全局答案。 

关键点是树的所有结构复杂性都被压缩为每个节点的度阈值。 每次插入只触及一个节点，因此更新是常数时间。 

### 为什么它有效

 不变的是，酷组件的最佳数量仅取决于树中存在多少“分支机会”，并且每个节点仅根据其程度独立做出贡献。 由于每条新边仅增加一个度，并且任何插入都不能减少现有度，因此贡献是单调的。 这可以防止任何必要的回溯或全局重新配置。 最多两个的红色邻接约束确保每个节点的贡献在一个小的常数度后饱和，使得全局目标可分解为局部计数器。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t, X = map(int, input().split())
    out_lines = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        deg = [0] * (n + 2)
        ans = 0

        res = []

        for i in range(1, n + 1):
            u = a[i - 1]

            old = deg[u]
            deg[u] += 1
            new = deg[u]

            if old >= 1:
                ans += 1

            if X == 1:
                res.append(str(ans))

        if X == 0:
            out_lines.append(str(ans))
        else:
            out_lines.extend(res)

    print("\n".join(out_lines))

if __name__ == "__main__":
    solve()
```该实现仅维护度数组和运行答案。 每当一个节点收到一个新的子节点时，我们都会检查它之前是否已经至少有一个子节点。 如果确实如此，第二个或后来的孩子会增加结构分支潜力，这对应于答案中的一个额外单元。 

X = 0 和 X = 1 之间的分离是通过仅累加最终值或存储每个查询的中间结果来处理的。 

微妙之处在于更新条件取决于先前的度数，而不是新的度数。 这避免了对第一个子项的重复计算，因为它还没有创建任何分支效果。

 ## 边缘情况

 一棵具有一个节点的最小树不会产生边，因此不会发生度更新，并且答案始终保持为零。 该算法自然地处理这个问题，因为没有触发更新条件。 

在纯链中，每个节点都附加到前一个节点，没有顶点达到二级，因此不会发生增量。 度数检查可防止任何错误计数，因为旧度数在更新时始终为零。 

在许多节点连接到同一中心的星形增长中，第一个连接之后的每个连接都会将答案增加一。 该算法正确地计算了所有次要子节点，因为中心的度数反复跨越阈值，而叶子仍然不相关。
