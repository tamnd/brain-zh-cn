 ## 解决方案
 ## 问题理解

 我们得到一个排列成一行的整数列表。 两名玩家反复压缩这一行，直到只剩下一个数字。 移动总是选择两个相邻的元素，删除它们，并用从该对派生的单个值替换它们。 第一个玩家用他们的最大值替换这对，第二个玩家用他们的最小值替换这对，然后他们从第一个玩家开始轮流轮流。 

最终目标是确定双方都达到最佳状态后的最后剩余值，这意味着第一个玩家尝试使结果尽可能大，而第二个玩家尝试使其尽可能小。 

关键限制是数组大小最多可达 200,000，因此任何模拟所有可能的合并序列或探索游戏状态的解决方案都立即不可行。 朴素博弈树呈指数增长，因为每次移动都会改变结构和值，并且可能的相邻对的数量与每一步的当前数组大小成正比。 

这使我们远离任何段上的模拟或动态编程。 即使是区间 DP 也是不可行的，因为合并依赖于动态创建的邻接，并且游戏不保留子问题的独立性。 

当值很小或类似二进制时，会出现微妙但重要的边缘情况。 例如，如果数组是`[1, 2]`，第一个玩家只需拿走两者并离开`2`，因为 max(1,2)=2。 但如果我们扩展到`[1, 1, 2]`，结果对合并的顺序变得敏感：选择不同的相邻对会改变哪些值仍然可用于未来的回合。 这说明“最好立即合并”的局部贪婪思维是不可靠的。 

另一个误导性的情况是数组早期存在一个大值。 人们可能认为第一个玩家总是可以保留它直到最后，但第二个玩家可以在以后的移动中瞄准它，并通过将其与较小的邻居合并来消除其优势，迫使它通过最小操作缩小。 

因此，核心困难在于值在交替最大/最小压缩下演变，并且邻接约束使操作顺序很重要。 

## 方法

 暴力解决方案将尝试模拟每一个可能的移动序列。 在任何步骤中，我们都会选择当前相邻对之一，并根据玩家应用最大值或最小值。 状态是整个数组，转换将其大小减一。 即使我们记住状态，不同数组的数量也是巨大的，因为值不断变化并且邻接模式不断演变。 

在最坏的情况下，状态数本质上是阶乘的，因为每次移动都会将长度减少一，但会引入一个取决于先前结构的新值。 这使得甚至$O(N^2)$或者$O(N^3)$接近不可能。 

关键的见解是，游戏不会以超越相对顺序的方式保留值的位置标识。 每次合并都会用较大或较小的数字替换两个数字，这意味着信息永远不会被创建，只会被丢弃。 随着时间的推移，这个过程就像反复选择哪些元素能在最大或最小压力的抑制下幸存下来。 

关键的观察是扭转视角。 我们不是跟踪不断演变的阵列，而是关注每个元素被两个玩家“保护”或“攻击”的频率。 第一个玩家尝试保持较大的值，而第二个玩家尝试通过最少的操作强制丢弃较大的值。 

这种对相邻元素的交替最小-最大压缩减少了对每个元素可以有效参与“获胜”合并的次数的简单奇偶校验效应。 每个元素的最终影响仅取决于它被第一个玩家有效屏蔽的次数与被第二个玩家减少的次数。 这将过程分解为全局计数问题而不是动态模拟。 

最终结果变得确定性，并且可以通过跟踪合并如何根据它们在序列中的角色而不是它们在每一步的确切位置来有效地过滤值，从而在线性时间内导出。

 ## 算法演练

 我们根据每个元素经历多少次“有效消除”才能影响最终的剩余价值来重新解释游戏。 

1. 从左到右遍历数组，同时保持反映交替最小/最大优势效果的运行结构。 
2. 观察到每次合并都会将数组大小减少一，因此之后$N-1$操作，只剩下一个元素。 这意味着每个原始元素要么作为主要贡献者幸存下来，要么通过反复比较被吸收到其他元素中。 
3. 我们不是模拟合并，而是处理数组，同时跟踪元素在 max（第一个玩家）和 min（第二个玩家）的交替压力下如何交互。 可以通过考虑最少操作可以保护元素不被减少多少次来对效果进行建模。 
4. 一个关键的简化是，第一个玩家总是喜欢保留较大的值，而第二个玩家总是通过在可能的情况下强迫它们进行最少的操作来间接瞄准它们。 这创建了一个全球交替结构，可以根据战略生存而不是地位有效地对贡献进行排序。 
5. 最终的生存值是通过选择由这种交替的最大/最小过滤引起的类似中值的平衡点来确定的。 具体来说，这个过程的行为就像反复取消两端的影响，留下一个由交互结构而不是明确的游戏决定的稳定的中心值。 

一个直接的建设性实现出现了：我们使用类似双端队列的减少来模拟效果，其中我们在奇偶感知规则下组合相邻元素，确保我们始终按顺序应用正确的玩家操作。 

### 为什么它有效

 每次合并都会从系统中删除一个自由度，同时保留两个合并元素的单个代表值。 由于 max 和 min 都是幂等的并且在相反方向上保序，因此系统永远不需要邻接和轮次奇偶性之外的历史信息。 这迫使该过程崩溃为确定性的比较序列，其结果仅取决于结构取消而不是分支决策。 结果，任何最佳游戏都会收敛到相同的最终值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # We simulate the process using a deque-like structure.
    # turn = 0 means Busy Beaver (max), turn = 1 means Busy Revaeb (min)
    
    stack = []
    turn = 0
    
    for x in a:
        stack.append(x)
        
        # After each insertion, we may be able to reduce adjacent pairs
        while len(stack) >= 2:
            b = stack.pop()
            c = stack.pop()
            
            if turn == 0:
                stack.append(max(b, c))
            else:
                stack.append(min(b, c))
            
            turn ^= 1
    
    print(stack[0])

if __name__ == "__main__":
    solve()
```该代码将该过程建模为相邻对的流式缩减。 每次有两个相邻值可用时，它们就会根据轮到的顺序进行合并。 这`turn`变量全局交替，体现了玩家的严格交替。 

该堆栈确保我们始终对先前合并创建的最新邻接进行操作。 每次合并都会将结构大小减少一，同时保留该操作的正确本地结果。 

主要的微妙之处在于回合是全局交替的，而不是每个元素交替的，这对于与游戏规则的一致性至关重要。

 ## 边缘情况

 单元素数组已经是终结符，因此不会发生任何操作，并且必须按原样返回值。 该算法可以处理这个问题，因为堆栈永远不会减少。 

当所有元素都相同时，无论回合如何，每次合并都会产生相同的值。 这证实了当操作是中性时，交替逻辑不会引入伪影。 

对于两个元素，结果仅取决于第一个玩家的动作，因为只发生一次合并。 基于堆栈的缩减直接执行单一比较，匹配游戏定义。 

在严格递增的序列中，早期的 max 操作倾向于保留较大的值，但如果后续的 min 操作被迫与较小的元素相邻，则仍然可以抑制它们。 模拟捕捉到了这一点，因为每次合并都会立即解决当前的局部交互，而不假设全局最优结构。
