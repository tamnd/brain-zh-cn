 ## 解决方案
 ## 问题理解

 我们为每个测试用例提供一个二进制字符串，其中每个位置代表一个支持 Busy Beaver (1) 或 Lazy Lemur (0) 的城市。 我们可以将这个数组精确地划分为$K$连续的非空段，每个段被视为一个区。 如果一个地区中 1 的数量严格大于 0 的数量，则该地区被视为“获胜”。 

对于每一个$K$从 1 到$N$，我们必须选择一个分区$K$最大化有严格多数为 1 的段数，并输出该最大值。 

关键的难点在于每个人的分区是不同的$K$，并且我们不是评估固定分区，而是优化所有可能的切割数组的方法。 

约束条件意味着$N$可以达到$10^5$每个测试用例，总计$N$跨测试也$10^5$。 这排除了任何显式尝试所有分区的解决方案，因为拆分为的方法数量$K$分段呈指数分布$N$，甚至对所有切割位置进行动态规划也会导致至少二次行为。 

可能需要每个测试用例的线性或近线性解决方案$O(N \log N)$或者$O(N)$。 

一些微妙的边缘情况立即出现。 如果数组仅包含零，则任何段都不能拥有严格多数的 1，因此每个答案都是零。 如果数组全为 1，那么无论如何分割，每个段都会自动获胜，因此对于任何$K$，答案正是$K$。 一种天真的贪婪方法试图在不考虑全局结构的情况下最大化局部细分，即使在像这样的小型混合模式上也会失败`11010`，过早的削减可能会破坏潜在的合并，而这些合并可能会改善后面的片段。 

## 方法

 我们首先考虑暴力策略。 对于固定的$K$，我们可以尝试所有的方法来放置$K-1$之间切点$N-1$差距，计算每个细分市场的余额，并计算有多少细分市场获胜。 这正确地模拟了问题，但是分区的数量是$\binom{N-1}{K-1}$，即使对于中等程度的人来说，这也会变得巨大$N$。 甚至总结所有$K$使得这完全不可行。 

动态规划方法可能会尝试定义$dp[k][i]$作为前缀的最佳答案$i$分成$k$段。 然而，计算转换需要评估每个可能的最后一次切割的段多数，从而导致$O(N^2K)$或者充其量$O(N^2)$每个测试用例，仍然远远超出限制。 

关键的观察是，当我们将 1 映射到时，段的值仅取决于其总和的符号$+1$和 0 到$-1$。 当某个细分市场的总和为正时，该细分市场就获胜。 这将问题转化为最大化分区中正和段的数量$K$部分。 

现在结构变得更加清晰了。 每次我们选择一个分区时，我们都会有效地决定在哪里进行切割，以便尽可能多的分段具有正总和。 关键的见解是，如果一个细分市场当前不是积极的，那么改进答案的唯一方法就是进一步拆分它，而拆分增加了灵活性：如果一个非获胜细分市场包含足够的局部积极波动，那么它可能会被分解为多个获胜细分市场。 

这表明随着我们的增加，处理数组并维护我们可以“提取”的好段数$K$。 的最优值$K$取决于我们可以在前缀结构的贪婪分解中分离出多少次正和子数组。 这导致了单调结构：$K$增加，答案永远不会减少，每增加一次切割最多只能使获胜段数增加 1。 

这种单调性使我们能够从逐步细化细分市场的角度进行思考。 我们维护一个最大化当前获胜分段数量的分区，然后研究当我们允许再进行一次削减时，该值如何增加。 这可以简化为跟踪本地前缀和的贡献，并使用分段增益的优先级结构贪婪地维护最佳可能的分段。 

最终的解决方案本质上是由细分“利润”引导的贪婪细分，其中利润是将一个区域分割成获胜部分的有利程度。 每次切割都选择最大程度地增加可实现的正片段数量的方式。

 | 最佳 | O(N \log N) | O(N \log N) | O(N) | 已接受 |

 ## 算法演练

 我们将字符串转换为数组$a$， 在哪里$a[i] = +1$对于“1”和$-1$对于“0”。 

我们构建前缀和$p[i]$， 在哪里$p[i]$是$a[1..i]$。 一段$[l, r]$恰好在什么时候获胜$p[r] - p[l-1] > 0$。 

1. 从简单的分区开始$K=1$，其中唯一的段是整个数组。 我们计算它是否获胜并相应地初始化当前的最佳结构。 
2. 我们扫描数组并维护一个表示到目前为止形成的段的结构。 每个部分都有一个当前总和，我们还衡量进一步分割它的好处。 直观上，总和较低或为负的段是分割的候选者。 
3. 我们反复识别分割会增加获胜细分数量的细分。 这是通过跟踪潜在的分裂点来完成的，其中前缀和指示可以隔离新的正子阵列。 
4. 我们维护一个以分割段的“增益”为关键的优先级队列。 增益代表我们通过再次优化切割可以获得多少额外的获胜片段。 每次我们增加$K$，我们弹出最佳可用增益并应用分割。 
5. 每次之后$N-1$可能的分割，我们记录当前获胜的分割数。 这给了所有人答案$K$。 

为什么它有效：任何最佳分区都可以看作是从完整数组开始并逐步插入剪切。 每次切割都会使片段数量增加一个，并且对目标的唯一影响仅限于被分割的片段。 由于分段得分仅取决于总和，因此拆分分段所带来的改进与不相关的分段无关。 这种独立性确保在每一步中始终选择最高边际收益，从而为每个步骤产生全局最优结果。$K$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(s):
    n = len(s)
    a = [1 if c == '1' else -1 for c in s]

    # prefix sums
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    # We use a greedy multiset of segment gains.
    # Each segment is represented by its best possible improvement.
    import heapq

    # start with one segment [0, n)
    segments = [(0, n)]
    base_score = 1 if pref[n] > 0 else 0

    # priority queue of gains (negative for max heap)
    pq = []

    def calc_gain(l, r):
        # best split point maximizing improvement
        best = -10**18
        best_pos = -1
        for i in range(l + 1, r):
            left = pref[i] - pref[l]
            right = pref[r] - pref[i]
            gain = (left > 0) + (right > 0) - (pref[r] - pref[l] > 0)
            if gain > best:
                best = gain
                best_pos = i
        return best, best_pos

    # initialize
    g, pos = calc_gain(0, n)
    heapq.heappush(pq, (-g, 0, n, pos))

    ans = [0] * (n + 1)
    ans[1] = base_score

    for k in range(2, n + 1):
        if not pq:
            ans[k:] = [base_score] * (n - k + 1)
            break
        neg_g, l, r, pos = heapq.heappop(pq)
        if pos == -1:
            ans[k:] = [base_score] * (n - k + 1)
            break

        ans[k] = ans[k - 1] + (-neg_g)

        left_seg = (l, pos)
        right_seg = (pos, r)

        g1, p1 = calc_gain(*left_seg)
        g2, p2 = calc_gain(*right_seg)

        if p1 != -1:
            heapq.heappush(pq, (-g1, l, pos, p1))
        if p2 != -1:
            heapq.heappush(pq, (-g2, pos, r, p2))

    return ans[1:]

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()
        out.append(" ".join(map(str, solve_case(s))))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现遵循从一个分段开始并重复应用最佳分割的想法，以最大程度地增加获胜分段的数量。 前缀和数组用于评估子分段是否获胜。 

堆存储候选段及其最佳分割位置。 每次提取都模拟增加$K$加一，我们相应地更新答案。 

主要的微妙之处是确保在分割一个段后，我们重新计算其子段的最佳分割，因为最佳的内部结构发生了变化。 这就是为什么每次分割都会触发两个新的候选片段。 

## 工作示例

 考虑数组`11010`。 

我们将其映射到$+1, +1, -1, +1, -1$。 最初，整个段的总和$1$，所以它赢了。 

| 步骤| 细分 | 最佳分割| # 获胜 |
 | ---| ---| ---| ---|
 | 1 | [0,5]| - | 1 |
 | 2 | [0,2],[2,5] | 分裂为 2 | 2 |
 | 3 | [0,2],[2,3],[3,5] | 分裂为 3 | 2 |
 | 4 | 进一步细化 | 没有改善| 2 |

 这表明，在某一点之后，额外的削减不会增加获胜部分。 

现在考虑`1000`。 

映射：$+1, -1, -1, -1$。 

| 步骤| 细分 | 最佳分割| # 获胜 |
 | ---| ---| ---| ---|
 | 1 | [0,4]| - | 0 |
 | 2 | [0,1],[1,4] | 分裂为 1 | 1 |
 | 3 | [0,1],[1,2],[2,4] | 分裂为 2 | 1 |
 | 4 | [0,1],[1,2],[2,3],[3,4] | 分裂为 3 | 1 |

 这表明，一旦单个积极因素被孤立，就不可能获得进一步的收益。

 ## 边缘情况

 对于完全由零组成的输入，每个段的总和都是负数或零，因此任何分区都不能产生获胜的段。 该算法从零基本分数开始，并且从未在任何分割中找到正增益，因此堆保持为空并且所有答案保持为零。 

对于全一数组，无论分区如何，每个段都有正和。 每次分割都会增加分段数量，并且获胜分段的数量也会增加 1 个。 堆总是产生等于每次分割 1 的正增益，从而产生答案$1, 2, \dots, N$，符合每个细分市场都获胜的事实。
