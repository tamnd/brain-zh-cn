 ## 解决方案
 ## 问题理解

 我们得到一个字符串和两个成本。 

第一个操作允许我们精确编码一个字符，成本为`a`。 

第二个操作允许我们以固定成本对任何非空子字符串进行编码`b`，但前提是该子字符串已经出现在已编码字符串部分的某个位置。 

必须从左到右处理字符串。 在每个位置，我们决定是否直接写入下一个字符，或者是否可以复制先前处理的前缀中已存在的较长子字符串。 

目标是最小化编码整个字符串所需的总成本。 

字符串的长度最多为 5000。这会立即排除任何具有大常数的指数甚至三次方。 动态规划的解决方案大致为$O(n^2)$工作通常是可以接受的$n=5000$， 尽管$O(n^3)$会太慢，因为它需要大约$1.25 \times 10^{11}$最坏情况下的操作。 

棘手的部分是确定对于每个位置，可以从已处理的前缀复制子字符串多长时间。 重复比较子字符串的简单实现很容易变得三次。 

一些边缘情况很容易被错误处理。 

考虑：```
3 3 1
aba
```最后一个`'a'`可能会被复制，因为它之前已经出现过。 最优答案是`7`， 不是`9`。 

考虑：```
4 1 100
aaaa
```复制成本极其高昂。 即使到处都存在重复的子串，最佳答案是`4`，通过单独写入每个字符获得。 

考虑：```
4 10 1
aaaa
```现在复制很便宜。 一种最佳构造是：```
"a"  -> 10
"a"  -> 1
"aa" -> 1
```总成本`12`。 

一个常见的错误是假设复制的子字符串必须作为先前选择的块出现。 问题只要求它是已经编码的前缀的子串。 前缀内的任何出现就足够了。 

另一个常见的错误是允许副本与未来的角色重叠。 编码位置时`i`，源出现必须完全位于已处理的前缀内`s[0..i-1]`。 

## 方法

 最直接的动态规划思想就是让`dp[i]`表示编码第一个的最小成本`i`人物。 

从位置`i`，我们总是可以对一个字符进行编码并移动到`i+1`有成本`a`。 

我们还可以尝试从以下位置开始的每个可能的子字符串`i`，检查之前是否出现过，如果出现过，直接用cost跳到该子串的末尾`b`。 

这个 DP 是正确的，因为每个有效的编码都对应于前缀长度之间的一系列转换。 

问题是检查子字符串是否已经出现。 如果我们尝试每个起始位置、每个长度，并直接比较字符串，我们大致得到$O(n^3)$工作。 

关键的观察是对于每个位置`i`，我们只需要一个数字：`mx[i] = maximum length of a substring starting at i that already occurs somewhere before i`。 

一旦知道了这个值，DP 就变得简单了。 如果`mx[i] = L`，然后每个长度`1`到`L`可以复制成本`b`。 由于成本不取决于长度，因此最好的选择始终是复制最长的可用子字符串。 

剩下的挑战是计算所有`mx[i]`。 

对于每对位置`(i, j)`和`j < i`，我们计算从以下位置开始的后缀的最长公共前缀`i`和`j`。 

让：```
lcp[i][j] = longest common prefix length of s[i:] and s[j:]
```然后任何事件开始于`j`提供长度可复制的子字符串：```
min(lcp[i][j], i - j)
```第二项至关重要。 源出现必须完全位于已处理的前缀内。 如果比赛超出位置`i-1`，我们不能使用该部分。 

取所有先前位置的最大值`j`给出`mx[i]`。 

LCP表可以计算为$O(n^2)$使用经典的反向DP：```
if s[i] == s[j]:
    lcp[i][j] = lcp[i+1][j+1] + 1
else:
    lcp[i][j] = 0
```一次`mx`已知，DP 变为$O(n^2)$，导致总体$O(n^2)$解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(n²) | 太慢了 |
 | 最佳 | O(n²) | O(n²) | 已接受 |

 ## 算法演练

 1. 读取字符串并创建一个`n × n`LCP 表。 
2. 从右下角到左上角填充表格。 

如果`s[i] == s[j]`，则公共前缀长度等于`1 + lcp[i+1][j+1]`。 否则为零。 
3. 对于每个位置`i`，计算最长的可复制长度`mx[i]`。 

检查每个较早的位置`j < i`。 

后缀匹配长度为`lcp[i][j]`，但只有第一个`i-j`字符完全属于已经编码的前缀。 因此可用长度为：```
min(lcp[i][j], i-j)
```取所有的最大值`j`。 
4.创建DP数组`dp`， 在哪里`dp[i]`是编码第一个的最小成本`i`人物。 
5. 初始化：```
dp[0] = 0
```6. 对于每个位置`i`：

 对一个字符进行编码：```
dp[i+1] = min(dp[i+1], dp[i] + a)
```7.如果`mx[i] > 0`，复制最长的可用子串：```
dp[i + mx[i]] = min(dp[i + mx[i]], dp[i] + b)
```由于所有副本长度的成本相同，因此使用最大长度支配所有较短的长度。 
8. 输出`dp[n]`。 

### 为什么它有效

 LCP 表正确测量两个后缀之间有多少个连续字符匹配。 

对于一个职位`i`，每个有效的复制块必须来自某个较早出现的位置，开始于`j < i`。 最长的这样的块有长度`min(lcp[i][j], i-j)`，因为只有完全位于已编码前缀内的字符才可以作为源。 取所有较早位置的最大值恰好给出了可用的最长复制操作`i`。 

DP 考虑了所有可能的方式来扩展已经最优的前缀编码。 一个转换对应于写入单个字符，另一个转换对应于使用最佳可用的复制操作。 由于复制成本与复制长度无关，因此较短的副本永远无法优于从相同位置开始的较长副本。 每个有效的编码都由一系列 DP 转换表示，每个 DP 转换代表一个有效的编码动作。 因此`dp[n]`等于可能的最小总成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    s = input().strip()

    lcp = [[0] * (n + 1) for _ in range(n + 1)]

    for i in range(n - 1, -1, -1):
        si = s[i]
        row = lcp[i]
        next_row = lcp[i + 1]

        for j in range(n - 1, -1, -1):
            if si == s[j]:
                row[j] = next_row[j + 1] + 1

    mx = [0] * n

    for i in range(n):
        best = 0
        for j in range(i):
            best = max(best, min(lcp[i][j], i - j))
        mx[i] = best

    INF = 10 ** 18
    dp = [INF] * (n + 1)
    dp[0] = 0

    for i in range(n):
        dp[i + 1] = min(dp[i + 1], dp[i] + a)

        if mx[i] > 0:
            dp[i + mx[i]] = min(dp[i + mx[i]], dp[i] + b)

    print(dp[n])

solve()
```第一部分构建 LCP 表。 向后计算可以保证当我们需要时`lcp[i+1][j+1]`，已经计算出来了。 

这`mx`数组存储每个位置可用的最大复制长度。 表达式`min(lcp[i][j], i-j)`是微妙的部分。 如果没有`i-j`限制，我们会错误地允许源出现扩展到尚未编码的字符。 

DP 存储前缀的最小成本。 从位置`i`，写一个字符总是可能的。 仅当以下情况时才可以进行复制`mx[i] > 0`。 

一个微妙的观察是我们只使用`mx[i]`，并非每个长度`1`到`mx[i]`。 因为每份副本的成本都是精确的`b`，较长的副本始终支配从同一位置开始的较短副本。

 ## 边缘情况

 考虑：```
4 10 1
aaaa
```在位置`2`，后缀开始于`0`和`2`长度匹配`2`。 该算法计算：```
min(lcp[2][0], 2) = min(2, 2) = 2
```所以`mx[2] = 2`。 DP直接从前缀长度跳转`2`前缀长度`4`为了成本`1`，产生正确答案`12`。 

考虑：```
4 1 100
aaaa
```存在相同的复制机会，但 DP 将它们与单独编写字符进行比较。 由于每份副本都需要花费`100`，所有的复制过渡都以字符过渡为主。 答案就变成了`4`。 

考虑：```
5 3 1
abcde
```每对后缀都有 LCP`0`，所以所有`mx[i]`价值观依然存在`0`。 DP仅使用字符转换和返回`15`。 

考虑：```
6 5 1
ababab
```在位置`2`, 子串`"ab"`已经出现在前缀中。 LCP表找到长度匹配`4`，但只有第一个`2`字符作为源是有效的，因为`i-j=2`。 该算法使用：```
min(4, 2) = 2
```防止与未来字符非法重叠。 这个限制正是保证解决方案正确的原因。
