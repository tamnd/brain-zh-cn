 ## 解决方案
 ## 问题理解

 我们给定一个起始值`a`, 结束值`b`，和一个参数`m`。 我们需要决定是否可以构造一个从 开始的正整数序列`a`，结束于`b`，并以非常具体的累积方式增长。 

在第一步之后的每一步中，新元素都是通过将所有先前元素相加而形成的，然后在两者之间添加一个“小”额外值`1`和`m`。 这意味着序列始终严格递增，并且每一步的增长很大程度上取决于前缀和的大小。 

所以核心问题不仅仅是我们能否达到`b`，但是我们是否可以使用一系列受控累积跳跃来达到它，其中每个跳跃相对于`m`。 

这些限制迫使我们进行建设性或贪婪的推理。 我们最多有 1000 个查询，值最多为 10^14。 这立即排除了对序列的任何状态空间搜索或对值的动态编程，因为前缀和呈指数增长，并且序列长度仅隐式有界。 

出现关键的结构边缘情况时`m = 1`。 在这种情况下，每一步都必须准确无误`prefix_sum + 1`，因此序列变得完全确定。 确定性增长与确定性增长之间的任何不匹配`b`使得答案变得不可能，甚至推理中的微小偏差也会破坏正确性。 

另一个微妙的情况是当`a`已经等于`b`。 一个简单的单元素序列是有效的，但任何强制执行至少一个转换的尝试仍然必须遵守“正整数加到前缀和”规则。 

最后，由于每个步骤都取决于整个前缀和，因此简单的前向构造往往会非常快地超调，使得在没有受控反向过程的情况下很难“瞄准”目标。 

## 方法

 直接的蛮力想法会尝试从以下位置构建序列：`a`。 在每一步中，我们维护当前的前缀和并尝试所有可能的值`r_i`在`[1, m]`，生成下一项并递归地继续。 这是正确的，因为它完全遵循定义，但分支因子是`m`，并且深度也会显着增长，因为值会快速上升。 尽管问题保证中序列长度上限为 50，`m`最多可达 10^14，因此这种方法是不可能的。 

关键的见解是递归在前缀和中是线性的。 如果我们定义`S_i = x_1 + ... + x_i`，那么过渡变为：`x_i = S_{i-1} + r_i`， 所以`S_i = 2S_{i-1} + r_i`。 

这将问题转化为构建`S_k = b + S_{k-1}`由加性有界噪声控制的指数增长。 该序列大约每一步加倍，因此向前工作不稳定，但向后工作变得自然。 

我们可以逆转这个过程：从`b`，我们尝试减去先前有效的前缀和。 自从`S_i = 2S_{i-1} + r_i`，我们得到：`S_{i-1} = (S_i - r_i) / 2`。 

为了使这一点有效，`(S_i - r_i)`必须是均匀的并且`r_i`必须位于`[1, m]`。 这会创建对可能的前辈的有界搜索。 由于序列长度很小（≤ 50），我们可以贪婪地或 BFS 式向后重建，直到达到`a`。 

该构造之所以有效，是因为在每一步，我们只需要确保一次向后转移的可行性，而指数收缩确保状态空间快速崩溃。

 | 蛮力 | 指数| 指数| 太慢了|
 | 最优（逆向构造） | O(50 · 每个查询的 m 选择剪枝) | O(50) | 已接受 |

 ## 算法演练

 1. 处理琐碎的情况`a == b`通过输出单元素序列。 不需要转换，因此约束条件得到了满足。 
2.从目标值开始`b`并将其解释为最终的前缀和`S_k`。 
3. 在每一步中，尝试找到有效的先前前缀和`S_{i-1}`这样`S_i - S_{i-1}`可以表示为`S_{i-1} + r_i`，这意味着`S_i = 2S_{i-1} + r_i`。 
4. 重新排列此关系以表达候选者`S_{i-1}`作为`(S_i - r_i) / 2`。 尝试值`r_i`从`1`到`m`使得这个整数为正数。 我们测试的原因`r_i`是它编码了每个步骤中允许的自由度。 
5. 当我们达到前缀和等于时停止`a`。 这保证了重建序列正确启动。 
6. 向后重建前缀和后，使用以下命令恢复原始序列值`x_i = S_i - S_{i-1}`。 

### 为什么它有效

 不变量是每个重构的前缀和满足反向形式的 m-cute 序列的定义递归。 每个后退步骤都强制执行一次有效的分解`S_i`进入`2S_{i-1} + r_i`和`r_i`在允许的范围内。 由于前缀和严格反向递减并保持正值，因此该过程必须在最多 50 个步骤内终止，并且通过可逆变换保留任何有效的构造。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        a, b, m = map(int, input().split())

        if a == b:
            print(1, a)
            continue

        # We store prefix sums backward
        seq = [b]

        # Try to reconstruct backwards
        ok = False

        # BFS-style limited search (since depth <= 50 guaranteed)
        from collections import deque
        dq = deque()
        dq.append((b, [b]))

        seen = set([b])

        while dq:
            s, path = dq.popleft()

            if len(path) > 50:
                continue

            if s == a:
                seq = path
                ok = True
                break

            # try previous prefix sums
            for r in range(1, m + 1):
                if s - r <= 0:
                    break
                if (s - r) % 2 != 0:
                    continue
                prev = (s - r) // 2
                if prev <= 0:
                    continue

                if prev in seen:
                    continue
                seen.add(prev)
                dq.append((prev, path + [prev]))

        if not ok:
            print(-1)
            continue

        # convert prefix sums to actual sequence
        path = seq[::-1]
        ans = [a]
        for i in range(1, len(path)):
            ans.append(path[i] - path[i - 1])

        print(len(ans), *ans)

if __name__ == "__main__":
    solve()
```该解决方案向后构建候选前缀和`b`使用逆递归。 队列存储部分重建状态，并且我们仅扩展从可能的派生的有效前驱候选者`r_i`价值观。 

微妙的部分是强制执行奇偶校验：只有`r_i`使`(S_i - r_i)`甚至可以产生一个整数前驱。 另一个重要的约束是当前缀总和低于以下值时提前停止`a`，因为进一步的扩张无法恢复。 

最后，一旦找到有效的前缀链，我们就通过相邻前缀和的差异将其转换回实际的序列值。 

## 工作示例

 ### 示例 1

 输入：```
a = 5, b = 26, m = 2
```我们从前缀和开始`26`。 

| 步骤| 当前 S | 选择 r | 上一个 |
 | --- | --- | --- | --- |
 | 1 | 26 | 26 2 | 12 | 12
 | 2 | 12 | 12 2 | 5 |

 我们到达`a = 5`，因此重建成功。 

这证实了向后分解可以通过受控减半来减少一个大值，与递归结构完全对齐。 

### 示例 2

 输入：```
a = 3, b = 9, m = 1
```从9开始，唯一可能的`r`是 1。 

| 步骤| 当前 S | r | 上一个 |
 | --- | --- | --- | --- |
 | 1 | 9 | 1 | 4 |
 | 2 | 4 | 1 | 1.5（无效）|

 我们陷入困境，因为奇偶校验失败，因此不存在有效的序列。 这表明当`m = 1`，这个过程变得僵化并很快暴露出不可能性。

 ## 边缘情况

 当`a == b`，算法立即输出一个单元素序列。 用于输入`a = 7, b = 7, m = 100`，不需要向后搜索，因为前缀和已经与目标匹配，并且基本满足正确性条件。 

什么时候`m = 1`，过渡变得僵化。 例如，从`a = 3, b = 9`，向后重建尝试`9 → 4 → 1.5`，由于非整数除法而失败。 该算法正确地拒绝了这种情况，因为在奇偶校验级别不存在有效的前驱，从而防止了任何错误的构造。
