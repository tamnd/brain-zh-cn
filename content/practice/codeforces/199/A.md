 ## 解决方案
 ## 问题理解

 我们得到一个整数`n`，并且该声明保证`n`本身就是一个斐波那契数列。 任务是代表`n`作为三个斐波那契数之和。 这三个值允许重复，并且零也是有效的斐波那契数，因为序列以`F0 = 0`。 

这个问题一开始听起来像是一个数论搜索问题，但约束条件完全改变了情况。 的价值`n`小于`10^9`，这意味着斐波那契数列包含很少的相关数字。 斐波那契数呈指数级增长，因此下面只有大约 45 个斐波那契数`10^9`。 即使对所有斐波那契值进行三次蛮力仍然足够小。 

最危险的错误是过度思考定理。 该声明试图表明我们需要证明或搜索分解，但输入已经保证是斐波那契数。 这立即创建了一个简单的结构。 

例如，如果输入是：```
5
```然后：```
0 0 5
```已经有效，因为所有三个数字都是斐波那契数，它们的总和是`5`。 

另一个容易犯的错误是忘记了`0`是斐波那契数列的一部分。 粗心的实现可能会生成从以下位置开始的斐波那契数`1, 1`，这会错误地拒绝有效答案，例如：```
1
```正确的输出可以是：```
0 0 1
```第三个微妙的情况是最小值：```
0
```正确的输出是：```
0 0 0
```某些实现意外地将零视为特殊的不可能情况，即使它本身就是斐波那契数。 

## 方法

 蛮力方法很简单。 首先生成每个斐波那契数`10^9`。 由于序列增长很快，因此该列表只有大约 45 个元素。 然后尝试每一个三元组`(a, b, c)`并检查是否：```
a + b + c = n
```这是有效的，因为搜索空间很小。 大约`45^3 ≈ 91,000`2 秒限制内的组合是完全可以接受的。 

暴力破解是正确的，因为它明确地检查了斐波那契数列的每种可能的组合。 这里的问题不是性能，而是不必要的复杂性。 我们正在解决一个比声明实际要求的更难的问题。 

关键的观察是输入本身保证是斐波那契数。 由于零也是斐波那契数，我们总是可以写：```
n = 0 + 0 + n
```这立即为每个可能的输入提供了有效的构造。 不需要搜索、动态规划或数论机制。 

问题实际上是测试我们是否注意到最简单的有效表示。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(k³) | O(k) | 已接受 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 这里`k`下面是斐波那契数列的个数`10^9`，大约45。 

## 算法演练

 1.读取整数`n`。 
2. 打印三个斐波那契数，其总和等于`n`。 
3.自从`0`是一个斐波那契数列并且`n`保证是斐波那契数列，输出：```

```1. 这种结构总是有效，因为：```
0 + 0 + n = n
```所有三项都是有效的斐波那契数。 

### 为什么它有效

 正确性直接来自问题保证。 斐波那契数列包含零，输入`n`也保证属于该序列。 该算法恰好输出三个斐波那契数，它们的总和等于所需的目标。 没有任何输入导致此构造失败。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

print(0, 0, n)
```有意将实现最小化，因为数学观察消除了问题的所有复杂性。 

程序读取给定的斐波那契数并立即打印`0 0 n`。 不需要生成斐波那契数列或验证任何内容，因为该语句已经保证了`n`是斐波那契。 

一个微妙的细节是零必须被视为有效的斐波那契数。 整个结构取决于这个事实。 由于序列是从开始定义的`F0 = 0`，输出总是合法的。
