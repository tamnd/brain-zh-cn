 ## 问题理解

 我们正在研究从 1 到 n 的一维数轴。 这条线上有两种类型的特殊点：p 个独立代理的起始位置（声明中称为猫虫）和 k 个传送门。 还有一个单一的目标位置g。 每个智能体都希望在最短的时间内达到 g。 

运动是确定性和均匀的：向左或向右迈一个单位需要一个时间单位。 改变这种线性运动的唯一方法是通过门户。 当代理到达门户位置时，它可以忽略它并继续正常行走，或者激活传送动作，在一个单位时间内将其发送到严格位于左侧或严格位于右侧的最近门户（如果存在这样的门户）。 

因此，底层结构是一条线上的点加上连续门户之间的特殊“跳跃边”的图形。 每个门户都连接到左侧和右侧最近的门户，形成一条链。 每个传送边的权重为 1，并且相邻整数位置之间的正常移动也是单位权重。 

我们必须为每个起始位置独立计算到达 g 的最短时间。 

约束很大：n 最大为 10^9，因此我们无法显式构建线路。 p 和 k 最大为 10^5，因此如果简单地重复，任何对门户的每次查询线性扫描都会太慢。 该结构是静态的，因此需要进行预处理。 

天真的解释可能会尝试在包含所有整数的图表上使用 Dijkstra 来模拟从每个起始位置开始的最短路径，但由于坐标范围的大小，这是不可能的。 即使仅限于门户，我们仍然必须有效地处理任意位置和门户之间的移动。 

一个微妙但重要的边缘情况来自于在到达时的门户选择。 例如，如果某个点位于门户上，代理可能会选择忽略它或立即传送，并且最佳策略可能要求在到达门户时并不总是使用门户。 

## 方法

 如果我们完全忽略门户，每个代理的答案就是到 g 的绝对距离。 当隐形传送无济于事时，这是正确的，并且它给出了基线 O(p) 解决方案。 

引入门户将问题转变为图上的最短路径，其中顶点是位置，但其中只有 k 个具有特殊的长范围边。 关键的观察结果是，除了门户位置和门户之间的段端点之外，我们永远不需要将任意位置视为决策点。 任何使用传送的最佳路径总是会到达某个传送门，可能是从非传送门位置步行之后。 

对于每个起始位置，暴力方法将运行 BFS 或 Dijkstra，其中我们将每个整数位置视为一个节点。 每个节点都会有到邻居和门户跳跃的边缘。 这会立即失败，因为状态空间的大小为 n，最大为 10^9。 

即使我们将节点限制为仅门户和起点/终点，我们仍然必须考虑任意点和门户之间的步行距离。 这建议将问题压缩到由排序门户定义的区间内。 

门户排序后，每个门户仅按排序顺序连接到其直接邻居。 这意味着传送在排序的门户列表上形成一个简单的线图。 剩余成本是从任何位置到附近传送门或直接到 g 的步行距离。

关键的见解是，一旦我们确定了点 x，任何通往 g 的最佳路径都只有几种结构形式。 我们要么直接走到g，要么首先走到某个传送门，可选地沿着传送门链传送，并最终从传送门退出到达g。 由于传送边的成本始终为 1 并连接相邻的门户，因此门户网络成为一条线上的最短路径问题，可以通过两次扫描进行预先计算。 

因此，我们可以使用排序后的门户数组上的双向 DP 预先计算从每个门户到 g 的最短距离，然后将其与从每个起点到其最近的门户的步行距离相结合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的直接最短路径（图扩展）| O(p·n) | O(p·n) | O(n) | 太慢了 |
 | 门户图预处理+每查询计算| O((p + k) log k) | O((p + k) log k) | O(k) | 已接受 |

 ## 算法演练

 我们对所有门户位置进行排序，使它们形成线性链。 

然后，假设我们已经站在该门户上，我们计算从每个门户开始到达 g 的成本。 这简化为大小为 k 的线图上的最短路径问题，其中每个门户都有到其相邻门户的边，成本为 1，此外每个门户可以直接走到 g，成本等于绝对距离。 

我们在排序的门户上分两遍执行动态规划松弛。 

首先，我们将 dp[i] 初始化为直接从入口 i 走到 g 的成本。 

然后我们从左到右扫描，从 dp[i-1] 加上相邻门户之间传送的成本更新 dp[i]。 

之后，我们从右向左扫动进行对称松弛。 在这两次通过之后，dp[i] 表示从门户 i 到 g 的最佳可能成本，无论是步行还是使用沿链的任何传送序列。 

一旦我们有了所有门户的 dp，我们就独立地回答每个起始位置。 

对于起始位置 x，我们计算进入门户系统的最佳方式。 这是通过使用二分搜索查找 x 左侧和右侧最近的门户来完成的。 

从 x 出发，我们可以直接走到 g，或者走到入口 i 然后支付 dp[i]。 

所以答案是直接距离 |x − g| 中的最小值 并且，如果存在左或右入口，|x − 入口| + dp[传送门]。 

### 为什么它有效

 传送门图是一个路径图，因此任何序列的传送都相当于沿着这条路径移动。 由于所有传送边具有相同的成本并且仅连接相邻节点，因此该结构上的最短路径完全由两个方向松弛捕获。 从门户到 g 的任何最佳路线都可以分解为从某个门户纯粹步行的最终路段和仅沿着门户链移动的早期路段。 DP 保证我们考虑沿链的两个方向，因此不会错过任何有益的弯路。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, p, k, g = map(int, input().split())
    a = list(map(int, input().split()))
    b = sorted(map(int, input().split()))

    # dp[i] = cost from portal i to g
    dp = [0] * k

    for i in range(k):
        dp[i] = abs(b[i] - g)

    # left to right relaxation
    for i in range(1, k):
        dp[i] = min(dp[i], dp[i-1] + 1)

    # right to left relaxation
    for i in range(k-2, -1, -1):
        dp[i] = min(dp[i], dp[i+1] + 1)

    # helper: lower_bound
    import bisect

    res = []
    for x in a:
        best = abs(x - g)

        i = bisect.bisect_left(b, x)

        if i < k:
            best = min(best, abs(x - b[i]) + dp[i])

        if i > 0:
            best = min(best, abs(x - b[i-1]) + dp[i-1])

        res.append(str(best))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```该代码首先对门户位置进行排序，以便列表中的邻接对应于线路上实际的左右邻接。 dp 数组存储从每个入口到出口 g 的已知成本。 初始值只是直接走到g。 

两个松弛过程在路径图上实现最短路径传播。 从左到右的通道允许通过其左侧邻居到达传送门，并加上一笔传送费用。 从右到左的传递对称地处理相反方向，确保信息沿着链在两个方向上传播。 

对于每个起始位置，我们使用二分搜索找到其最近的门户邻居。 只有这两个候选者很重要，因为进入门户系统的任何最佳路径都必须首先到达门户，并且任一方向上最近的入口点支配所有其他入口点。 然后，我们将到达该门户的步行成本与其预先计算的 dp 值结合起来，并与直接步行到 g 进行比较。 

一个常见的陷阱是忘记起点可能已经是一个门户或者可能位于两个门户之间； 这两种情况都可以通过二分法考虑两个邻居来自然地处理。 

## 工作示例

 考虑示例输入：```
n=10, p=2, k=2, g=7
a = [2, 8]
b = [4, 7]
```我们首先将门户排序为 [4, 7]。 

初始 dp 值为：

 | 我| 门户| |传送门-g| |

 |---|--------|-------------|

 | 0 | 4 | 3 |

 | 1 | 7 | 0 |

 从左到右松弛后：

 | 我| dp 之前 | dp 之后 |
 | --- | --- | --- |
 | 0 | 3 | 3 |
 | 1 | 0 | 最小值(0, 3+1)=0 |

 从右到左松弛后：

 | 我| dp 之前 | dp 之后 |
 | --- | --- | --- |
 | 1 | 0 | 0 |
 | 0 | 3 | 最小值(3, 0+1)=1 |

 最终 dp = [1, 0]。 

现在评估查询：

 对于 x = 2，直接成本为 5。最近的门户为 4，成本为 |2-4| + dp[0] = 2 + 1 = 3。 

对于 x = 8，直接成本为 1。最近的门户为 7，成本为 |8-7| + dp[1] = 1 + 0 = 1。 

这与示例输出 3 1 匹配。 

此跟踪显示门户 4 变得有用只是因为它可以廉价地路由通过门户 7。

 | 测量 | 复杂性 | 说明|

 | 时间 | O((p + k) log k) | O((p + k) log k) | 排序门户占主导地位，每个查询都使用二分搜索|

 ## 边缘情况

 一种微妙的情况是起始位置恰好位于门户上。 在这种情况下，平分结果指向该门户索引，算法自然会考虑 dp[i]，而不需要额外的处理。 例如，如果 x 等于 b[i]，则成本变为 dp[i]，这正确地允许立即使用传送或直接行走。 

另一种情况是只有一个门户时。 然后，两次松弛过程都没有任何意义，并且 dp 简化为简单值 |b[i] - g|。 答案正确地变为 min(|x - g|, |x - b[0]| + |b[0] - g|)，这符合门户只能充当中继而不是链的直觉。 

最后一种边缘情况是入口完全位于 g 的一侧。 DP 仍然有效，因为直接步行初始化已经捕获了正确的距离，并且沿链传播不会引入无效的捷径。
