 ## 解决方案
 ## 问题理解

 我们得到一个奇数长度的数组。 该进程运行的长度恰好是向下舍入的一半，并且每次循环在允许数组中某处的单个相邻交换后总是删除前两个元素。 

交换的位置不受限制，但仅限于每轮一个相邻的交换。 之后，前两个元素被永久删除，剩下的后缀成为下一轮的新数组。 这一直持续到只剩下一个元素为止，任务是通过最佳选择交换来最大化最终的幸存者。 

关键的难点在于，交换是全局选择，但效果是局部的，而删除总是固定在前面。 这就造成了元素因重复删除而向前漂移的速度有多快，以及我们可以使用每轮最多一次交换来延迟或加速这种漂移的程度之间的紧张关系。 

约束允许 n 最大为 2 × 10^5，这排除了尝试所有可能的交换决策或跟踪阵列的所有可能状态的任何模拟。 任何根据每轮或每个位置的选择进行分支的解决方案都会呈指数或至少呈二次爆炸。 

当人们假设最佳策略总是将最大元素向前冒泡时，就会出现幼稚推理的微妙失败案例。 这种直觉被打破了，因为前面正是交换后立即发生删除的地方。 例如，在像 [1, 100, 2, 3, 4] 这样的小数组中，如果过早地陷入前两个位置，重复向前推 100 仍然会失败，因为删除是无条件的。 

另一个误导性的情况是假设答案始终是全局最大值。 在[10,6,2,1,5,3,4]中，最大值为10，但它不可能存活下来，因为无论交换如何，它在删除过程中都被过早删除。 

## 方法

 蛮力视图是模拟每一轮，并在每一轮删除前两个元素之前尝试所有可能的相邻交换。 即使我们只跟踪一个数组，交换位置的选择每轮都会创建 O(n) 分支，并且有 O(n) 轮，导致可能的序列呈指数级增长。 即使是每轮尝试所有交换位置的简单模拟，在最佳确定性解释中也已经花费了 O(n^2) 次操作，这对于 n 高达 2 × 10^5 来说太慢了。 

关键的见解是，该过程实际上并不是关于本地重排能力，而是关于针对固定删除计划的生存。 每轮都会从前面删除两个元素，因此每个元素的命运取决于它在被淘汰之前可以避免漂移到前两个位置的时间。 每轮一次交换仅允许元素每轮最多将其有效位置移动一步，而删除每轮将所有内容向左移动两步。 

这创建了一个线性漂移模型：由于删除压力，每个元素向左移动两个，并且可以使用交换每轮最多向右推动一个。 最终效果是，每个元素只能“延迟”其死亡一定量，并且该界限仅取决于其初始位置，而不取决于其他元素的值。 这将问题分解为确定哪些指数能够存活到最后一轮。 

一旦建立了这个视角，问题就简化为确定能够在所有回合中生存的位置后缀，然后取其中的最大值。

 ## 算法演练

 我们现在将生存推理转化为直接计算。 

### 算法演练

1. 观察有 (n − 1) / 2 轮，每一轮从前面删除恰好两个元素，因此该过程删除除一个元素之外的所有元素。 
2. 跟踪最初位于位置 i 的元素。 在没有交换的 k 轮之后，由于删除，它左移了 2k 个位置，因此它的有效位置变为 i − 2k。 
3. 使用每轮单次交换作为修正机制。 每轮最多允许一次相邻交换，因此在 k 轮中，一个元素最多可以相对于删除漂移向右推 k 个位置。 
4. 结合两种效果。 k 轮之后，最初位于 i 的元素的最佳情况有效位置是 i − 2k + k，可简化为 i − k。 
5. 要使一个元素存活到最后一轮 k = (n − 1) / 2，此时其有效位置必须保持为正。 这给出了条件 i − (n − 1) / 2 > 0。 
6. 这简化为 i > (n − 1) / 2，这意味着只有数组后半部分的元素才可能存活到末尾。 
7. 因此，最终答案是基于 1 的索引中从 (n + 1) / 2 到 n 的索引中的最大值。 

### 为什么它有效

 删除过程确定性地每轮从前面删除两个元素，这为每个元素创建了严格的向左漂移。 该算法提供的唯一控制是通过单个相邻交换对每轮至多一个位置进行有界向右修正。 由于两种效应均随轮数线性变化，因此任何元素的净位移也是线性的，并且完全由其起始索引决定。 

这意味着生存不受数组深处任意元素对之间的相对顺序变化的影响，而仅受元素是否可以避免在最后一轮之前进入删除区的影响。 一旦一个元素在前半部分开始，其最大可能的向右修正不足以抵消重复删除，因此它最终必须被删除。 后半部分的元素有足够的余量，可以在删除窗口之外保留足够长的时间，从而存活到最后。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    start = n // 2  # 0-based index of (n+1)/2 in 1-based
    print(max(a[start:]))

if __name__ == "__main__":
    solve()
```该实现直接应用导出的生存边界。 唯一的微妙之处是索引：在基于 0 的索引中，幸存的段从 n // 2 开始。 

其余的就是后缀上的直接最大值。 不需要模拟，因为互换的所有动态行为已经被吸收到生存不平等中。

 ## 边缘情况

 一个关键的边缘情况是最大元素位于数组的前半部分。 在这种情况下，人们很容易认为交换总是可以挽救它，但重复删除引起的漂移超出了有限的交换预算。 

对于输入：```
5
100 1 2 3 4
```该算法选择后缀 [2, 3, 4]，并返回 4。元素 100 从位置 1 开始，但每轮都会从前面删除两个元素，并且每轮的单个交换无法补偿在过程早期始终位于删除区域内的情况。 

另一个边缘情况是统一数组，例如：```
5
7 7 7 7 7
```这里每个策略都会产生相同的最终值。 后缀规则仍然适用，并且算法通过取最后三个元素中的最大值正确返回 7。
