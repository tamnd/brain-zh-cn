 ## 解决方案
 ## 问题理解

 我们得到一个数字序列并允许执行固定数量的操作。 每个操作都会选择一个位置并将该值恰好减一。 总共执行 k 次后，我们希望最大化有多少个指数成为“山谷”。 

山谷是一个内部位置 i，这意味着它不能是第一个或最后一个元素，因此在所有修改后其值严格小于两个邻居。 因此，对于选定的减量配置，我们尝试对数组进行整形，以便许多内部点成为局部最小值。 

重要的限制是每个操作都是极其局部的：它只减少一个元素。 我们从不增加值，因此在位置 i 创建山谷的唯一方法是确保 ai 与 ai−1 和 ai+1 相比足够小，方法是降低 ai 或不要过多降低其邻居。 

输入大小n最大为10^5，k最大为10^9。 数组值也可以很大。 这种组合立即排除了任何超过 k 次操作的模拟。 任何有效的解决方案都必须推理出在结构上可以形成多少个山谷以及每个山谷需要多少“努力”。 

当山谷重叠时，就会出现一个微妙的问题。 如果我们试图贪婪地在每个位置独立地强制形成一个山谷，我们可能会低估共享成本或过多计算可实现的山谷，因为改变一个元素会影响两个潜在的山谷条件。 另一个失败的情况是假设仅降低中心始终是最佳的，而有时根据高度差异降低邻居的成本更便宜。 

## 方法

 蛮力的想法是模拟操作并尝试跨位置分配 k 减量的所有可能性。 在每个假设分布之后，我们检查存在多少个山谷。 这相当于以所有可能的方式将 k 个单位减少分布在 n 个位置上，这在组合上是巨大的。 即使忽略枚举，评估单个配置也是 O(n)，并且配置的数量是星和条的数量级，远远超出了可行的限制。 

一种更有结构性的蛮力是贪婪地一一建造山谷。 对于每个候选位置 i，我们计算需要多少减量才能使 ai 严格小于两个邻居（假设邻居是固定的）。 然后我们反复挑选最便宜的山谷。 这会失败，因为一旦我们修改索引，附近山谷的成本就会发生变化，因此本地重新计算仍然会导致每个选择重复 O(n) 次扫描，从而得到 O(n^2)。 

关键的观察结果是，山谷以一种非常具体的方式相互独立：i 处的山谷仅取决于三元组 (i−1, i, i+1)。 如果我们确定位置 i 是山谷，唯一的要求是 ai 必须严格小于两个邻居。 由于我们只能减少值，因此我们永远不想增加邻居。 因此，形成山谷的最佳策略是只减少ai，而不是其邻居，因为降低邻居只会使其他山谷变得更难，而不会帮助这个山谷。 

因此，对于固定的 i，使其成为山谷的成本为：

 成本(i) = max(0, min(ai−1, ai+1) − (ai − 1) + 1)

 这简化为：

 成本(i) = max(0, ai − min(ai−1, ai+1) + 1)

 每个山谷的成本都是独立的，因为我们在建造它时从不接触邻居。 因此，问题简化为选择尽可能多的索引 i ，使得它们的成本总和不超过 k。 

这成为一个经典的贪婪选择问题：计算所有成本，对它们进行排序，然后首先选择最小的成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数 / O(n^2) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

我们专注于将问题转化为独立的“谷成本”，然后选择预算下的最大数量。 

1. 对于从 2 到 n−1 的每个索引 i，计算 m = min(ai−1, ai+1)。 该值表示 ai 必须低于该阈值才能成为山谷。 
2. 如果 ai 已经严格小于 m，则 i 已经是需要零运算的谷候选者。 否则，计算所需的减量数量为 cost = ai − m + 1。这是使 ai 严格小于两个邻居所需的最小量。 
3. 将所有此类成本收集到一个列表中。 每个成本代表在不影响任何其他位置的情况下“激活”该位置的山谷的成本有多大。 
4. 按非降序对成本列表进行排序。 这种排序确保我们优先考虑创建成本最低的山谷。 
5. 遍历排序列表，同时维护已使用操作的运行总和。 对于每个成本，如果相加不超过 k，则将其包括在内并增加答案。 否则，停止或跳过进一步的包含。 
6. 返回选定谷的数量。 

### 为什么它有效

 每个谷值要求都是三元组的局部要求，并且可以纯粹通过减少中心元素来满足。 由于运营只会降低价值，接触邻居永远不会帮助降低另一个山谷的成本； 它只会带来间接增加其他地方成本的风险。 因此，每个山谷可以被视为具有固定价格的独立项目。 任务变成最大化总预算下的项目数量，其中最小成本的贪婪选择是最优的，因为每个项目具有相同的价值（一个谷）并且仅成本不同。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    costs = []
    
    for i in range(1, n - 1):
        m = min(a[i - 1], a[i + 1])
        if a[i] < m:
            costs.append(0)
        else:
            costs.append(a[i] - m + 1)
    
    costs.sort()
    
    ans = 0
    used = 0
    
    for c in costs:
        if used + c <= k:
            used += c
            ans += 1
        else:
            break
    
    print(ans)

if __name__ == "__main__":
    solve()
```该代码直接实现了从形成山谷到独立成本的减少。 内部索引的循环计算每个位置所需的最小减量。 排序至关重要，因为它确保我们始终首先在最便宜的山谷上进行操作，从而在固定预算 k 下最大化计数。 

一个微妙的实施细节是处理已经有效的山谷，其中成本为零。 这些应该首先采取，因为它们不消耗任何操作。 贪心循环自然会立即包含它们。

 ## 边缘情况

 第一个边缘情况是当 n ≤ 2 时。该算法自然会生成一个空的成本列表，因为没有内部索引。 例如，输入`n=2`始终返回 0，因为没有位置可以满足山谷定义。 

另一种情况是数组，其中许多谷值无需任何操作就已经有效。 用于输入`5 0`和数组`[5,1,5,1,5]`，每一个内部位置都已经是一个山谷了。 计算出的成本全部为零，因此算法选择所有这些成本而不消耗 k。 

第三种情况是当 k 非常大但结构限制谷时。 为了`[10,9,8,7,6]`，每个内部位置的成本为 2，因此如果 k=100 仍然尊重最多存在两个位置，则只能选择两个谷。 即使预算无关，贪心选择仍然会返回正确的结构最大值。
