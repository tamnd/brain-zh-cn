 ## 解决方案
 ## 问题理解

 该任务将数组纯粹描述为一种从零开始索引的方式。 如果数组有长度$n$，其有效索引从$0$最多$n - 1$。 然后，问题要求我们输出这样一个数组的最后一个元素的索引，当只有长度时$n$被给出。 

因此，输入是表示概念数组大小的单个整数，输出是该数组中最大的有效索引。 换句话说，我们将长度转换为基于零的索引下的最后一个位置。 

约束条件$1 \le n \le 100$意味着输入非常小，因此从恒定时间到线性时间的任何计算都可以轻松通过。 然而，问题的结构不需要元素迭代或任何模拟。 输出仅取决于数组大小与其最终索引之间的直接算术关系。 

除了可能的最小输入之外，没有任何有意义的边缘情况。 什么时候$n = 1$，该数组在索引处有一个元素$0$，所以正确的输出是$0$。 任何错误地假设索引从 1 开始的方法都会输出$1$，这已经超出了有效范围。 

## 方法

 一个天真的解释是显式构造数组的想法，然后通过迭代位置来计算其最后一个索引。 人们可能会想象创建一个序列$0$到$n - 1$，然后返回遇到的最后一个元素。 这可以正确工作，因为它反映了索引的定义，但它执行了不必要的工作：生成所有索引需要$O(n)$即使最终答案已经仅由长度决定，也可以进行操作。 在最坏的情况下，这意味着最多 100 次迭代，这在这里仍然微不足道，但对于更大的约束，该结构会变得浪费。 

关键的观察是，从零开始的索引定义了一种固定的关系：最后一个有效索引始终比数组的大小小一。 这消除了构造或遍历数组的任何需要。 该问题完全简化为计算单个减法。

 ## 算法演练

 1.读取整数$n$来自输入，表示数组的长度。 该值保证至少为 1，因此数组始终至少有一个有效索引。 
2. 计算$n - 1$，它对应于最后一个有效的从零开始的索引。 
3. 直接输出计算值。 

### 为什么它有效

 在零索引数组中，第一个元素位于索引 0 处，每个附加元素都会将索引增加 1。 放置后$n$元素，最终到达的位置正是$n - 1$。 这种关系对于每一个有效的$n$在输入域中，因此计算$n - 1$无一例外总是产生正确的最后一个索引。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    print(n - 1)

if __name__ == "__main__":
    solve()
```该解决方案读取单个整数并立即应用数组大小​​和最后一个索引之间的派生关系。 执行一次减法，并打印结果。 不需要循环、条件或额外的内存结构。 使用`strip()`即使输入包含尾随空格（这在竞争性编程环境中很常见），也能确保安全解析。

 ## 边缘情况

 唯一在结构上有意义的边缘情况是数组长度最小时。 用于输入$n = 1$，计算直接进行：读 1，减 1，输出 0。这与单元素数组只有索引 0 的事实相符。任何偏离减法规则的情况都会立即破坏这种情况，这使其成为整个逻辑的有用的正确性锚点。
