 ## 解决方案
 ## 问题理解

 我们有一组参加编程竞赛的参赛者。 每个参赛者都解决了一组问题，这组问题被编码为从 A 到 Z 的不同大写字母的字符串。字符串的长度就是解决问题的数量。 例如，“ACD”这样的字符串表示参赛者解决了三个问题。 

排名规则是按字典顺序分两层进行的。 首先，参赛者按照解决问题的数量进行排序，解决的问题越多，总是排在解决问题较少的参赛者之前。 其次，在解决相同数量问题的参赛者中，他们的相对顺序取决于罚时。 关键的问题是没有给出处罚时间。 我们只知道解决的计数，并且我们想要计算如果我们分配与规则一致的任意不同的惩罚时间，则可能有多少种不同的完整排名。 

因此，不确定性完全存在于等长字符串组内。 每个长度相等的组可以在其自身之间任意排列，而组的全局顺序通过减小长度来固定。 

输入大小 n 最大可达 100000。每个字符串最多 26 个字符。 这立即排除了对参赛者所有排列的任何阶乘枚举或任何显式模拟惩罚分配的尝试。 即使在大小为 k 的单个组内，当 k 很大时，k 阶乘也变得不可行。 

一个微妙的点是字符串不一定是唯一的。 多个参赛者可以拥有相同的解决集，但由于保证罚时时间不同，因此它们在顺序上仍然是可区分的。 这意味着相同的字符串仍然表现为同一存储桶中的单独元素。 

一个天真的错误是认为我们只需要按长度排序，然后乘以组大小的阶乘。 这实际上在数学上是正确的，但是直接计算阶乘而无需模块化算术处理和预计算仍然可以。 真正隐藏的问题不是阶乘的大小，而是确保我们正确地按长度分组并计算重数。 

另一个微妙的边缘情况是所有参赛者都有不同的长度。 在这种情况下，只有一个有效排名，因为排序是完全确定的。 粗心的方法可能仍然会乘以一组大小的阶乘，这很好，但通常表示对分组逻辑的误解。 

## 方法

 暴力解释是考虑与独特性一致的所有可能的惩罚时间分配并计算归纳的排序顺序。 对于每个作业，我们都会得出参赛者的排列，并计算出现了多少个不同的排列。 由于惩罚时间仅在等长组内相关，因此这简化为考虑每个组内的所有排列。 

如果我们关注一组大小为 k 的组，则内部排序的数量是 k 阶乘。 由于组是独立的，因此总答案是组大小与所有长度值的阶乘的乘积。 

蛮力观点之所以有效，是因为惩罚时间只会导致等长类内的总排序，而不会影响跨类排序。 然而，显式地生成或推理惩罚分配是不必要的并且太慢。 观察结果是，惩罚排序相当于在每个固定大小的桶内选择任意排列。 

因此，问题简化为通过解决的计数对参赛者进行分组，并将组大小的阶乘乘以模数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解惩罚| O(n!) | O(n) | 太慢了 |
 | 按规模+阶乘分组| O(n + 26) | O(26) | 已接受 |

 ## 算法演练

 我们将每个可能的已解决计数视为一个桶。

1. 对于每位参赛者，计算他们的绳子长度。 这是影响跨组排名的唯一值。 
2. 统计有多少参赛者属于从 0 到 26 的每个长度值。由于每个字符串长度最多为 26，因此我们只需要一个大小为 27 的固定大小的数组。这使得每个参赛者的分组时间恒定。 
3. 预先计算最多 n 模 1e9+7 的阶乘。 这是必要的，因为每个组都贡献一个阶乘项，如果重复直接计算会太慢。 
4. 将答案初始化为 1。 
5. 对于每个长度桶，将答案乘以阶乘[计数]，其中计数是该桶中参赛者的数量。 如果 count 为 0 或 1，则贡献为 1 并且不会改变答案。 乘法反映了该组内可能的内部惩罚顺序的数量。 
6. 输出对 1e9+7 取模的最终结果。 

为什么它有效来自于排名规则的结构。 所有参赛者均按已解决的计数划分为等价类别。 类之间的全局排序是固定的，并且严格按大小递减，因此类之间不可能存在交错。 在每个类别中，惩罚时间仅被限制为不同的，这相当于选择该类别的排列。 由于班级是独立的，因此排名总数是每个班级的排列的乘积，而这正是班级规模的阶乘的乘积。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n = int(input())
cnt = [0] * 27

lengths = []
for _ in range(n):
    s = input().strip()
    cnt[len(s)] += 1

fact = [1] * (n + 1)
for i in range(1, n + 1):
    fact[i] = fact[i - 1] * i % MOD

ans = 1
for c in cnt:
    ans = (ans * fact[c]) % MOD

print(ans)
```该实现首先将输入压缩到按字符串长度索引的频率桶中。 这避免了单独存储或对参赛者进行排序，因为只计算重要的内容。 

阶乘表在线性时间内构建一次。 这是至关重要的，因为每个桶乘法都需要快速访问阶乘值。 

最后，答案累加每个桶大小的阶乘。 由于交换律，乘法的顺序是无关紧要的，但迭代所有 27 个可能的长度可以保持逻辑简单并避免丢失任何组。 

一个常见的实现错误是忘记多个参赛者可以共享相同的字符串长度，这会错误地将组大小减少为 1 并产生答案 1。另一个错误是在循环内重复重新计算阶乘而不是预先计算。 

## 工作示例

 考虑示例输入：```
ABC
ABCD
ABCD
DBAE
```我们计算长度：3,4,4,4。所以频率桶是：

 | 步骤| 长度 3 | 长度 4 |
 | --- | --- | --- |
 | 读取输入后| 1 | 3 |

 现在阶乘：1！ = 1, 3! = 6。 

| 桶| 计数 | 贡献|
 | --- | --- | --- |
 | 3 | 1 | 1 |
 | 4 | 3 | 6 |

 答案变为 1 × 6 = 6。 

这表明只有大小为 3 的组才贡献任何变异性。 单一元素组没有任何贡献。 

另一个构造的例子：

 输入：```
A
B
C
D
```所有长度均为 1，因此一桶的尺寸为 4。 

| 长度| 计数 |
 | --- | --- |
 | 1 | 4 |

 贡献度为4！ = 24，这意味着处罚时间的任何排列都会产生不同的排名。 

这证实了当所有参赛者都在已解决的计数上并列时，答案就变成了完整的排列计数。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 一次计算长度，一次遍历 27 个桶，加上阶乘预计算 |
 | 空间| O(n) | 最多 n 的阶乘数组和常数桶数组 |

 约束条件允许 n 最大为 100000，因此具有较小常数因子的线性时间很容易在限制范围内。 内存使用量主要由阶乘数组主导，并且在 512 MiB 以内。 

## 测试用例```python
import sys, io

MOD = 10**9 + 7

def solve():
    input = sys.stdin.readline
    n = int(input())
    cnt = [0] * 27
    for _ in range(n):
        s = input().strip()
        cnt[len(s)] += 1

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    ans = 1
    for c in cnt:
        ans = ans * fact[c] % MOD

    print(ans)

def run(inp: str) -> str:
    global output_capture
    old_in = sys.stdin
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    old_out = sys.stdout
    sys.stdout = out
    solve()
    sys.stdout = old_out
    sys.stdin = old_in
    return out.getvalue().strip()

# sample
assert run("3\nABC\nABCD\nABCD\nDBAE\n") == "6"

# minimum size
assert run("1\nA\n") == "1"

# all distinct lengths
assert run("3\nA\nAB\nABC\n") == "1"

# all same length
assert run("4\nA\nB\nC\nD\n") == "24"

# mixed
assert run("5\nA\nB\nC\nDE\nDE\n") == str((2*1) % MOD)

 ## 边缘情况

 一个重要的边缘情况是每个参赛者都有不同数量的已解决问题。 例如：```
A
AB
ABC
```该算法形成大小为 1、1 和 1 的桶。每个桶贡献阶乘 (1)，即 1，因此最终答案为 1。排名完全固定，因为没有两个参赛者共享惩罚顺序可能不同的类别。 

另一种情况是所有参赛者共享相同的字符串：```
A
A
A
A
```所有产品均装在 4 号尺寸的一桶中，生产 4 个！ = 24. 该算法正确地将相同的解决集视为独立的参赛者，因为即使解决的集相同，惩罚时间也保证了不同的排序。 

最后一个微妙的情况是大 n 只填充了几个长度值。 例如，如果所有字符串的长度都是 26 或 25，我们仍然可以正确地累积阶乘，而无需以有意义的方式迭代未使用的存储桶。 无论分布如何，固定的 27 大小数组都可确保正确性。
