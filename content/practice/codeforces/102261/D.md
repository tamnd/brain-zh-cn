 ## 解决方案
 ## 问题理解

 我们有一串字符。 解码轮查找以下形式的三个连续字符的每次出现`~XY`， 在哪里`X`和`Y`是十六进制数字，并将每个这样的三元组替换为 ASCII 代码为十六进制数字的单个字符`XY`。 一轮中的所有替换同时发生。 

我们没有被要求重建最终的解码字符串。 我们只需要连续非平凡回合的最大数量，这意味着至少存在一个这样的三元组的回合。 

有趣的是，替换可以创建另一个波形符。 尤其，`~7e`变成带有ASCII码的字符`0x7e`，这是另一个`~`。 新的波形符可以参与下一轮的模式。 替换还可以创建一个十六进制数字，该数字稍后可能会被左侧的波形符消耗。 

输入长度最多为 300,000，因此扫描整个字符串一次的算法是合适的。 花费二次时间的算法太慢。 这很重要，因为解码轮数本身可以是线性的。 例如，字符串`~7e7e7e`减少为`~7e7e7e`， 然后`~7e7e`， 然后`~7e`， 然后`~`，所以轮数与输入长度成正比。 

因此，在每轮之后显式构造字符串的简单实现可以执行大约 300,000 次完整扫描。 由于每个重要轮次都会将长度减少至少两倍，因此最坏的情况包含大约 150,000 轮，并且检查的字符总数可以达到 θ(n²)，在每轮只减少一个模式的链中大约为 n²/4。 

有几种很容易被忽略的边缘情况。 

为了`~7e7e`，第一轮变化`~7e`进入`~`，离开`~7e`。 第二轮将其更改为`~`，所以答案是 2。仅搜索原始字符串的实现会找到一种模式并错过新创建的波形符。 

为了`~~37~45~fF`, 三种模式`~37`,`~45`， 和`~fF`全部都存在于初始状态并且必须在同一轮中被解码。 在那一轮之后，字符串包含`~7E`接下来是解码后的`0xFF`角色，所以另一轮是可能的。 正确答案是 2。将每次替换视为单独一轮的顺序实现可能会错误地计算这些操作。 

为了`~00`，替换生成 ASCII 代码 0，该代码不可打印并且位于输入字母表之外。 它仍然必须在内部表示为字符值。 正确答案是 1，并且生成的字符不能启动另一个编码。 

为了`~7g`，三元组无效，因为`g`不是十六进制数字。 什么也没有发生，所以答案是 0。仅检查两个字符是否是字母会错误地接受这种情况。 

大写和小写十六进制数字均有效。 因此`~7E`是一个有效的模式并且答案为 1。 

## 方法

 直接的方法是精确模拟解码过程。 在一轮中，从左到右扫描当前字符串。 每当`~XY`找到后，将解码后的字符附加到下一个字符串并跳过三个位置。 否则追加当前字符不变。 扫描结束后，用新构造的字符串替换当前字符串，然后重复，直到找不到任何模式。 

该模拟是正确的，因为它精确地遵循回合的同时定义。 模式不能重叠：在前导之后`~`，接下来的两个字符必须是十六进制数字，因此另一个模式不能从这些位置中的任何一个开始。 问题是它的运行时间。 一次重要的回合将字符串长度减少至少两倍，因此可以有 θ(n) 轮。 如果每轮只有一个图案消失，则扫描的长度大约为`n, n-2, n-4, ...`，它给出 θ(n²) 字符处理。 对于 n = 300,000，这是数百亿次运算。 

关键的观察是我们实际上不需要具体化每个中间字符串。 每次替换都会创建一个新角色，并且该角色有一个明确定义的轮数。 

想象一下，每个当前字符都是一个包含两个值的对象：它的 ASCII 代码和创建该字符的轮次。 原始字符的轮数为0。假设三个相邻的对象形成`~XY`。 只有在所有三个对象都存在后才能进行替换，因此新角色会出现在回合中`1 + max(depth of the three objects)`。 

这将整个过程变成了一个归约树。 我们可以在扫描原始字符串时在本地构建这些缩减，而不是全局模拟回合。 

堆栈就足够了，因为每个编码的三元组都会消耗三个相邻的当前字符并生成一个字符。 当附加一个新字符时，唯一新可能的模式是以该字符结尾的模式或通过紧邻该字符之前的缩减创建的模式。 我们可以在堆栈顶部反复减少此类模式。 与每个结果字符一起存储的深度正是它出现的回合。 

这适用于同时回合的关键原因是两个有效模式永远不会重叠。 如果某个模式当前可用，则减少它不会使另一个当前可用的模式失效。 使用新字符的后续模式只是接收更大的深度，这恰好对应于等待下一轮解码。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最优堆栈| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 预先计算每个可能字节的十六进制值。 对于角色`0`通过`9`,`A`通过`F`， 和`a`通过`f`，存储从 0 到 15 的值。每隔一个字符都会收到一个无效标记。 这避免了重复的字符串搜索并直接处理十六进制表示法的两种情况。 
2. 从左到右扫描输入。 对于每个原始字符，将其 ASCII 代码与深度 0 一起压入堆栈。原始字符在第一轮解码之前就已经存在。 
3.压入一个字符后，检查最后三个堆栈条目是否具有以下形式`~XY`。 这些条目表示当前缩减字符串的相邻字符，因为之前的每个缩减都用一个堆栈条目替换了连续的块。 
4. 如果最后三个条目形成有效模式，则将其删除并计算解码后的 ASCII 代码：`16 * value(X) + value(Y)`。 它的深度比三个删除条目的最大深度大一。 
5. 将生成的字符及其计算出的深度推回到堆栈中。 新字符代表原始输入的整个缩减块。 
6. 当堆栈顶部包含有效模式时，重复归约检查。 新创建的字符可以在其前面紧邻两个字符形成一个模式，因此仅检查一次就会错过减少链。 
7. 保持曾经产生的最大深度。 该深度是连续非平凡解码轮的最大数量。 

### 为什么它有效

 在执行了该块内部的所有归约之后，保持每个堆栈条目代表原始字符串的一个连续块，并且其存储深度恰好是其当前字符出现的一轮。 

当三个相邻条目形成时`~XY`，相应的字符在其存储深度过去后同时存在。 所有这三个都出现的最早的一轮比它们的最大深度大，因此替换它们会准确地产生真实过程在该轮中创建的角色。 由于有效模式不能重叠，因此在本地执行此减少不会干扰同一轮中应发生的另一次减少。 

堆栈所做的每一次归约都对应于一次真正的解码操作，并且每一次真正的解码操作最终都作为堆栈上的有效三元组可见。 因此，最大的存储深度正是最后一个重要的回合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def decode_rounds(s: str) -> int:
    hex_value = [-1] * 256

    for i in range(10):
        hex_value[ord('0') + i] = i

    for i in range(6):
        hex_value[ord('A') + i] = 10 + i
        hex_value[ord('a') + i] = 10 + i

    stack_char = []
    stack_depth = []

    answer = 0

    for ch in s:
        stack_char.append(ord(ch))
        stack_depth.append(0)

        while len(stack_char) >= 3:
            c0 = stack_char[-3]
            c1 = stack_char[-2]
            c2 = stack_char[-1]

            if c0 != 126:
                break

            v1 = hex_value[c1]
            v2 = hex_value[c2]

            if v1 == -1 or v2 == -1:
                break

            d = max(
                stack_depth[-3],
                stack_depth[-2],
                stack_depth[-1]
            ) + 1

            value = 16 * v1 + v2

            stack_char.pop()
            stack_char.pop()
            stack_char.pop()

            stack_depth.pop()
            stack_depth.pop()
            stack_depth.pop()

            stack_char.append(value)
            stack_depth.append(d)

            if d > answer:
                answer = d

    return answer

def main() -> None:
    s = input().rstrip('\n')
    print(decode_rounds(s))

if __name__ == "__main__":
    main()
```十六进制查找表构建一次。 使用由 ASCII 代码索引的数组使得检查字符常数时间，并且它自然地处理从 0 到 255 的解码值。 

两个堆栈保持平行。`stack_char`存储每个缩减块的当前字符，同时`stack_depth`存储该角色存在的回合。 保持数组分离可以避免每次推送或减少字符时分配元组。 

每个输入字符都被推送一次。 成功的归约会删除三个条目并添加一个条目，因此每次归约都会使堆栈大小减少两倍。 最多可以有`floor(n / 2)`减少。 内部`while`因此，循环总共只执行 O(n) 次，即使它嵌套在扫描中。 

边界检查`len(stack_char) >= 3`在阅读最后三个要素之前，这是必要的。 十六进制表还可以处理 33 以下和 126 以上的解码字符，没有任何特殊情况，因为所有内部字符都简单地由其整数 ASCII 值表示。 

Python整数具有任意精度，因此深度计算不存在溢出问题。 实际上，最大深度最多为`floor((n - 1) / 2)`。 

## 工作示例

 考虑样本`~7eFf`。 前三个字符的形式`~7e`，解码为另一个波形符。 新的波形符后面紧接着是`Ff`，因此可以进行第二次减少。 

| 输入字符 | 缩减后堆叠字符 | 最大深度|
 | --- | --- | --- |
 |`~`|`~`| 0 |
 |`7`|`~7`| 0 |
 |`e`|`~`| 1 |
 |`F`|`~F`| 1 |
 |`f`|`ÿ`| 2 |

 加工后`e`，堆栈包含深度为 1 的波形符。处理`F`和`f`完成另一个有效的三元组，因此解码的字符具有深度 2。以后不可能进行缩减，给出答案 2。这演示了在一轮中生成的字符可以参与后续一轮的中心思想。 

现在考虑样本`~~37~45~fF`。 

| 输入字符 | 缩减后堆叠字符 | 最大深度|
 | --- | --- | --- |
 |`~`|`~`| 0 |
 |`~`|`~~`| 0 |
 |`3`|`~~3`| 0 |
 |`7`|`~7`| 1 |
 |`~`|`~7~`| 1 |
 |`4`|`~7~4`| 1 |
 |`5`|`~`| 2 |
 |`~`|`~~`| 2 |
 |`f`|`~~f`| 2 |
 |`F`|`~ÿ`| 2 |

 读完后`7`, 子串`~37`成为角色`7`，给出深度1。读完后`5`，堆栈暂时形成`~7E`，它本身就是一个有效的编码，因此减少为`~`深度2.决赛`~fF`变成`0xFF`在深度 1 处并且不会创建另一个波形符。 最大深度为 2。 

该表还显示了为什么堆栈可以执行原始字符串中不存在的减少。 什么时候`~7E`出现后，它代表了字符串在一轮真正的解码后的状态，因此在构造归约树时立即归约它相当于模拟第二轮。

 ## 边缘情况

 对于链条`~7e7e`，堆栈首先读取`~7e`并将其替换为深度为 1 的波形符。剩余的`7e`现在紧接在生成的波形符之后，因此堆栈形成另一个有效的三元组，并将其替换为深度为 2 的波形符。最终堆栈仅包含该波形符，答案为 2。这捕获仅检查原始输入模式的实现。 

为了`~~37~45~fF`，初始模式是同时的。 堆栈减少`~37`到`7`深度为 1，则`~45`到`E`深度为 1。这两个缩减暴露了`~7E`，变成深度为 2 的波形符。最后的`~fF`变成`0xFF`深度为 1。答案是 2。这捕获了将单个替换与解码轮次混淆的实现。 

为了`~00`，堆栈将这两个数字识别为有效的十六进制数字并生成整数值 0。深度变为 1，并且生成的零字节无法形成新的模式，因为它不是波形符。 答案是 1。该算法从不假设中间字符是可打印的，这是必要的，因为解码值可以占据整个字节范围。 

为了`~7g`，第一个字符是波形符并且`7`是一个有效的十六进制数字，但是`g`有查找价值`-1`。 堆栈使所有三个字符保持不变，因此不会计算任何减少，答案为 0。这说明了为什么十六进制验证必须完全接受`0`通过`9`,`A`通过`F`， 和`a`通过`f`。 

对于最大尺寸的链条`~`随后是 149999 份`7e`进而`!`，长度正好是300000。每轮去掉第一个`7e`从活跃链中离开并留下另一条`~7e`模式，因此正好有 149999 轮。 决赛`!`防止任何额外的回合。 这是答案的最坏结构情况，也说明了为什么逐轮模拟可能需要二次时间。 

对于由 300000 个波形符组成的字符串，没有波形符后跟两个十六进制数字，因此堆栈从不执行归约。 每个条目的深度都是 0，答案仍然是 0。这证实了该算法不会意外地将波形符本身视为编码。
