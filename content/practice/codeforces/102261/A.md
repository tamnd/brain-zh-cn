 ## 解决方案
 ## 问题理解

 每个 (N) 个闹钟在其自己的初始时间 (t_i) 开始响铃，然后每 (X) 分钟重复一次。 如果多个警报同时响起，阿列克谢只会听到一次该时刻。 他在听到第 (K) 次不同的铃声后立即醒来。 

任务是找到第 (K) 个不同时间。 

约束足够大，足以排除模拟每个振铃事件的可能性。 可以有（10^5）个报警，而（X）和（K）都可以达到（10^9）个。 答案本身可能约为 (10^{18})，因为单个闹钟可能需要响 (K) 次。 显式生成前 (K) 个事件的解决方案在最坏的情况下可能需要 (O(KN)) 工作，这是完全不可行的。 我们需要对答案大小的对数依赖性，以及大致线性的预处理。 

主要的边缘情况来自同时发生的警报。 考虑```
2 5 3
1 6
```两个闹钟在完全相同的时刻响起：(1,6,11,\ldots)。 第三个不同的振铃时间是 (11)。 如果粗心的解决方案将每次警报响起视为单独的事件，则会将 (1) 和 (6) 计数两次并产生错误的答案。 

另一个微妙的情况是两个初始时间具有相同的模 (X) 余数，但不相等：```
2 5 4
1 11
```第一个闹钟在 (1,6,11,16,\ldots) 响铃，第二个闹钟在 (11,16,\ldots) 响铃。 第二个警报根本不贡献新​​的响铃时间，因此第四个不同时间是 (16)。 简单地将每个 (t_i) 保留为独立的算术级数会重复计算 (11,16,\ldots)。 

相反的情况也很重要。 不同的模 (X) 留数永远不会发生碰撞。 例如，```
2 5 4
1 2
```产生 (1,2,6,7,\ldots)。 这两个级数永远保持不同，因为模 (5) 具有不同余数的数字不可能相等。 

## 方法

 直接的解决方案可以重复找到所有闹钟中最早的下一次响铃时间，计数一次，然后将此时响铃的每个闹钟提前。 这在概念上是简单且正确的，因为它实际上模拟了振铃时刻的合并序列。 然而，即使一个警报也可以产生(K)个事件，并且(K)可以是(10^9)。 对于(N=10^5)，维护所有警报可能需要大约(NK)、最多(10^{14})次操作。 即使使用优先级队列的更仔细的模拟仍然必须处理 (K) 个不同的时刻，至少给出 (O(K\log N))，这太大了。 

有用的结构是每个级数都有完全相同的步骤 (X)。 当两个警报的开始时间具有相同的模 (X) 余数时，它们可以同时响起。 假设同一残基类别中的两个起始点是 (a) 和 (b)，且 (a<b)。 由于(b-a)是(X)的倍数，因此第二个闹钟的每次响铃时间也是第一个闹钟的响铃时间。 因此，只有每个残留类别中最早启动的警报才重要。 

对于每个余数模 (X)，用最早的 (t_i) 替换所有警报后，我们最多有 (X) 个相关级数，并且每个级数都是

 [
 s,\s+X,\s+2X,\l点
 ]

 其中 (s) 是其最早开始时间。 

现在考虑候选时间 (T)。 对于从 (s) 开始的一个级数，不超过 (T) 的振铃时刻数为

 [
 \左\lfloor\frac{T-s}{X}\右\rfloor+1
 ]

 当 (s\le T) 时，否则为零。 由于不同的保留级数具有不同的模 (X) 残基，因此它们永远不会重叠。 因此，我们可以将这些计数相加，以获得最多 (T) 的不同振铃时刻的准确数量。 

该计数是单调的：增加 (T) 只能增加振铃时刻。 这使得二分搜索适用。 我们对至少发生 (K) 个不同振铃时刻的最小 (T) 进行二分搜索。 最小的 (T) 正是第 (K) 个振铃时刻。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(K\log N)) 与优先级队列 | (O(N)) | 太慢了|
 | 最佳| (O(N\log A)) | (O(N)) | 已接受 |

 这里(A)是答案的大小，最多约为(​​10^{18})，因此二分查找只需要大约60次迭代。 

## 算法演练

 1. 读取 (N)、(X)、(K) 和起始时间 (t_i)。 
2. 按起始时间的余数 (X) 对起始时间进行分组。 对于每个余数，仅保留最小的开始时间。 

如果两个开始具有相同的余数，则后面的进程完全包含在前面的进程中。 保持最小值可以在二分搜索开始之前消除所有重复的未来响铃时刻。 
3. 定义计数函数（count(T)）。 对于每个保留的开始时间 (s)，如果 (s\le T)，则添加

 [
 \frac{T-s}{X}+1
 ]

 使用整数除法。 

结果值恰好是 (T) 处或之前的不同振铃时刻的数量，因为保留的级数具有不同的残基，因此不能相交。 
4. 选择包含答案的二分查找区间。 最早可能的振铃时间为 (\min(t_i))。 安全上限是

 [
 \min(t_i)+(K-1)X。 
]

 即使从最短时间开始的单个进程到那时也包含 (K) 个事件，因此实际答案不能更大。 
5. 二分查找满足 (count(T)\ge K) 的最小 (T)。 如果中点处的计数已经至少为 (K)，则答案最多为该中点，因此将右边界向左移动。 否则，答案更大，因此将左边界向右移动。 
6.输出最终的左边界。 这是至少出现 (K) 个不同事件的第一次，这意味着它恰好是第 (K) 个不同的响铃时间。 

### 为什么它有效

在仅保留每个残留模 (X) 的最早警报后，每个删除的警报仅产生由相同残留的保留警报已经产生的时刻。 因此，保留的进程生成与原始警报完全相同的响铃时间集。 

保留的级数具有成对不同的模 (X) 残基，因此它们中的任何两个都不能同时响起。 因此，对每个进程中的事件数量进行求和即可得出截至任意时间 (T) 的不同事件的确切数量。 该计数是单调的，因此 (count(T)\ge K) 中的最小 (T) 恰好是第 (K) 个不同事件的时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, X, K = map(int, input().split())
    t = list(map(int, input().split()))

    INF = 10**30
    earliest = {}

    for value in t:
        r = value % X
        if r not in earliest or value < earliest[r]:
            earliest[r] = value

    starts = list(earliest.values())
    first = min(starts)

    def count_events(T):
        total = 0

        for s in starts:
            if s <= T:
                total += (T - s) // X + 1
                if total >= K:
                    return total

        return total

    lo = first
    hi = first + (K - 1) * X

    while lo < hi:
        mid = (lo + hi) // 2

        if count_events(mid) >= K:
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```字典`earliest`实现残差级压缩。 关键是`value % X`，其值为具有该余数的最小开始时间。 我们不需要保留实际的警报身份，因为只有它们响起的时刻才重要。 

功能`count_events`评估二分搜索使用的单调谓词。 条件`s <= T`是必要的，因为当警报第一次响铃时间在 (T) 之后时，警报尚未产生任何事件。 对于积极的进展，`(T - s) // X + 1`对 (s) 本身的事件进行计数，这是常见的相差一错误的来源。 

早返时`total >= K`是一种优化。 一旦计数达到 (K)，其确切的较大值与二分搜索谓词无关。 

Python 整数具有任意精度，因此潜在的大值`first + (K - 1) * X`不溢出。 在具有固定宽度整数类型的语言中，这里需要 64 位整数。 

即使有许多残基类别，上限也是有效的，因为一个级数从`first`单独包含 (K) 个振铃时刻`first + (K - 1) * X`。 更多的警报只能使第（K）个事件更早发生。

 ## 边缘情况

 当每个闹钟的开始时间相同时，例如```
5 10 7
3 3 3 3 3
```只有一个不同的级数（3,13,23,33,43,53,63,\ldots）。 该字典包含一个条目，因此`count_events(63)`是(7)，答案是(63)。 对警报而不是不同时间进行计数的模拟会错误地认为在时间 (3) 发生了五个事件。 

当两个起点相差 (X) 的倍数时，例如```
2 5 4
1 11
```两个起始点都有残基 (1)。 (11) 的级数是 (11,16,21,\ldots)，它已经包含在 (1,6,11,16,\ldots) 中。 字典只保留 (1)，给出第四个事件 (16)。 这就是为什么需要按余数分组，而不是仅仅删除相等的开始时间。 

当两个警报具有不同的残基时，它们的事件永远不会发生冲突。 为了```
2 5 4
1 2
```合并序列从 (1,2,6,7) 开始，所以答案是 (7)。 计数函数给出 (count(6)=3) 和 (count(7)=4)，因此二分查找返回 (7)。 这也测试了不充分候选者和第一个充分候选者之间的界限。 

最小情况```
1 1 1
1
```只有一个进展并要求其第一个事件。 二分搜索的下限和上限均为 (1)，因此循环不执行迭代并立即返回 (1)。 这证实了搜索间隔包括答案本身，而不是严格从答案之后开始。
