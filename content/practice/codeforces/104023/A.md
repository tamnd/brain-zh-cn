 ## 解决方案
 ## 问题理解

 我们了解了五位置竞技比赛中冠军球队的历史。 每支过去的冠军球队都由五名指定球员组成，每个固定位置有一名球员，从 1 到 5。从这段历史来看，有些球员是已知的冠军，并且每个这样的球员都有一个固定的位置，在球队之间不会改变。 

现在我们还获得了即将举行的锦标赛的球员名单。 这些玩家中的每一个也都有一个已知的固定位置。 然而，我们不知道他们将如何分组。 

目标是从给定的池中组建尽可能多的有效团队。 一支有效的球队必须由五名不同的球员组成，从 1 到 5 的每个位置各有一名球员，并且每支球队必须至少包括一名以前获得过冠军的球员。 

每位球员最多只能在一支球队中使用，并且某些球员可能不会被使用。 

因此，任务是最大化不相交的完整 5 人团队的数量，使得每个团队至少包含一名历史冠军球员。 

约束足够小，我们可以扫描所有玩家并执行贪婪或组合分组。 对于最多 1000 名玩家，任何大致线性或线性算数的解决方案就足够了。 即使涉及对按位置分组的数组进行少量恒定次数的解决方案也是可以接受的。 

一个关键的微妙之处在于，球员有固定的位置，因此一支球队并不是由五个人组成的任意分组，它恰好是从位置 1 到位置 5 中的一个人。这种结构消除了位置之间的任何组合匹配复杂性：我们每个位置只选择一名球员。 

另一个重要的一点是，我们不需要最大化球员的总使用量，只需要最大化完整球队的数量。 这表明贪婪的打包方法而不是像流这样的全局优化。 

一个典型的错误是尝试首先分配所有冠军或贪婪地组建团队而不跟踪每个位置的可行性。 另一个错误是忽略了每支球队必须至少包含一名冠军，这造成了位置之间的耦合约束。 

## 方法

 一个蛮力的想法是考虑所有可能的方法，将玩家分组为大小为 5 的球队，然后检查每个分组是否满足冠军约束。 然而，即使我们忽略对称性，将多达 1000 名玩家分成 5 人一组的方法数量也是巨大的。 这使得暴力破解完全不可行。 

问题的结构大大简化了事情。 由于每支球队的每个位置必须只有一名球员，因此我们可以按位置将球员分开。 令 cnt[i] 为位置 i 的可用球员数量。 那么最大球队数量受到最小 cnt[i] 的限制，因为每个球队每个位置消耗一名球员。 

所以唯一真正的问题是，我们能否确保这些潜在球队中，每支球队都至少有一名冠军球员。 

我们可以将球员分为两类：冠军球员和非冠军球员。 对于每个位置，我们计算存在多少个冠军和存在多少个非冠军。 

我们首先观察到，如果我们组建 k 支球队，我们必须从每个位置上恰好挑选 k 名球员。 因此，对于每个位置 i，我们总共至少需要 k 名球员。 

现在我们还要求每支队伍至少有一名冠军。 这相当于说，在所有选定的 5k 名选手中，至少有 k 名是冠军，但分布得使得每个队伍都有覆盖范围。 

更直接、更简单的看法是，从逐一填补团队的角度贪婪地思考。 对于固定的k，我们需要检查可行性：我们是否可以从每个位置挑选k名球员，使得每支球队都至少有一名冠军？ 这变成了类似二分的可行性问题，但由于位置固定，它崩溃为计数条件。

一个有用的转变是认为非冠军是“自由填充者”，而冠军是“团队主力”。 每支队伍必须至少消耗一名冠军，因此队伍总数不能超过所有位置的冠军选手总数。 这给出了一个上限。 

另一方面，每个位置必须有足够的球员总数来支持k支球队。 所以 k 受总计数位置的最小值和总冠军的限制。 

这些界限被证明是足够的：如果我们将 k 设置为（最小位置数）和（总冠军数）的最小值，我们总是可以通过首先贪婪地分配冠军并用任何剩余球员填充每个位置的剩余空位来构建有效的团队。 

因此，最佳策略就是计算这两个量并取它们的最小值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分区| 指数| 指数| 太慢了 |
 | 计数+贪婪可行性| O(n + m) | O(1) 到 O(m) | 已接受 |

 ## 算法演练

 1. 阅读所有历史冠军球队并收集所有曾经作为冠军出现的名字。 还要记录他们的固定位置。 这给了我们一个集合，让我们可以识别当前池中的玩家是否是冠军。 
2. 读取当前池中的 m 个玩家。 对于每个球员，根据其位置以及是否是冠军进行分类。 维护两个数组 cnt[pos] 和 champ[pos]，每个数组大小为 5。cnt 计算每个位置的玩家总数，champ 计算每个位置的冠军数量。 这种分离是必要的，因为团队受到严格的位置限制。 
3. 计算total_champions 作为champ[pos] 所有位置的总和。 这代表了可用于满足每支球队必须至少包含一名冠军的要求的“强制贡献者”总数。 
4. 计算 max_complete_by_position 作为 cnt[pos] 1..5 中 pos 的最小值。 如果我们忽略冠军限制，这是可能的完整 5 位置球队的最大数量，因为每支球队每个位置消耗一名球员。 
5.答案是min(total_champions, max_complete_by_position)。 这是在尊重结构约束（五个不同位置）和每个团队至少包含一名冠军的要求的情况下可以组建的最大团队数量。 

### 为什么它有效

 每支球队都需要来自五个独立位置桶中的每一个的一名球员，因此球队的数量从根本上受到最小桶大小的限制。 另外，每支球队都需要至少一名冠军，因此每支球队必须至少消耗全球冠军组中的一个元素。 由于冠军不受超出其固定任务的位置限制，因此他们充当了全球限制资源。 任何组成 k 支队伍的建筑都必须至少使用 k 个冠军，因此 k 不能超过可用冠军的总数。 反之，如果满足这两个约束，则可以通过先为每队分配一名不同的冠军，然后从剩余球员中任意填补剩余位置来组建球队，确保可行性且不发生冲突。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    champ_names = set()

    for _ in range(n):
        parts = input().split()
        for name in parts:
            champ_names.add(name)

    m = int(input())

    cnt = [0] * 6
    champ_cnt = [0] * 6

    for _ in range(m):
        name, pos = input().split()
        pos = int(pos)
        cnt[pos] += 1
        if name in champ_names:
            champ_cnt[pos] += 1

    total_champions = sum(champ_cnt)
    max_by_pos = min(cnt[1:6]) if m > 0 else 0

    print(min(total_champions, max_by_pos))

if __name__ == "__main__":
    solve()
```该代码首先构建一组所有冠军名称，因此成员资格检查的时间是恒定的。 然后它会按位置汇总玩家，同时计算其中有多少人是冠军。 

关键的决定是总冠军数和瓶颈位置数之间的最后分钟。 这直接编码了两个独立的约束：完整位置的可用性和每支球队所需冠军的可用性。

 ## 边缘情况

 一种微妙的情况是，冠军存在但只集中在一个位置。 例如，如果所有冠军都是位置 1 的玩家，但其他位置没有冠军，只要我们有足够的非冠军来填补剩余位置，并且每支球队至少有一名冠军来自位置 1，那么团队仍然是可能的。该算法可以正确处理此问题，因为无论分布如何，total_champions 仍然会计算所有可用的锚点，并且 min(cnt[pos]) 强制执行结构可行性。 

另一种情况是，每个位置上都有足够的球员，但根本没有冠军。 在这种情况下，champ_cnt 的总和为零，因此即使 min(cnt[pos]) 可能很大，结果也为零。 这正确地反映了没有一支球队能够满足“至少一个冠军”的要求。 

最终边界是当一个位置为空时。 那么 min(cnt[pos]) 为零，无论冠军是否可用，都会强制答案为零。 这是正确的，因为如果五个职位都没有被填补，就无法组建有效的团队。
