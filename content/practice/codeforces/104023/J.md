 ## 解决方案
 ## 问题理解

 给定一个整数的多重集$a_1, a_2, \dots, a_n$。 每一步都包括选择一个元素并将其减少$1$。 随着时间的推移，元素向下漂移，直到最终变成$0$。 

此外，一些值$x$有一个上限$limit_x$任意时刻允许它们在数组中出现多少次。 如果一个值没有约束，那么它实际上是无界的。 

如果执行后出现任何值，则移动是非法的$x$超过了它的极限。 特别是，当我们从$v$到$v-1$，我们减少$v$并增加计数$v-1$，因此只有目标值可能会变得无效。 

如果玩家没有合法的动作，他们就输了。 当所有值都为零时，或者当每个可能的减量都会立即违反约束时，就会发生这种情况。 

任务是当双方都发挥最佳且 Pico 先走时确定获胜者。 

这些限制意味着我们无法逐步模拟游戏。 所有测试用例的总大小是$10^5$，因此任何解决方案在涉及的不同值的数量上都必须本质上是线性的或接近线性的。 

当值恰好达到其极限时，就会出现微妙的边缘情况。 在这种情况下，任何向其中移动更大值的尝试都会被禁止，从而有效地阻止进一步向下流动。 这可能会产生“障碍”，将价值线分割成独立的区域。 

## 方法

 直接模拟将重复选择一个元素并尝试在检查所有约束的同时减少它。 每次移动都需要更新两个频率计数并验证所有约束值。 由于最多可以有$10^9$作为值并且最多$10^5$动，这种做法是行不通的。 

关键的观察结果是，约束影响游戏的唯一方式是阻止相邻值之间的转换。 当我们从$x$到$x-1$，我们增加计数$x-1$。 如果$x-1$已经到了极限，这一招是禁止的。 一旦有一个值$x$饱和（其计数等于其极限），它成为永久屏障：没有元素可以移动到其中$x$再次，因为这会立即违反约束。 

这将整数行划分为独立的段。 在每个段内，元素只能向下移动，直到它们达到下方最接近的饱和值，该饱和值充当吸收边界。 在这样的一段内，每次减量只是将质量向下移动，直到所有元素都塌陷到边界上，并且有效移动的数量恰好是超出该边界的总和。 

因此，游戏简化为计算在一切被迫停止之前我们可以减少元素多少次。 每次减量都是一次移动，因此无论策略如何，移动总数都是固定的，最佳玩法仅决定谁走最后一步。 根据有效步数总数的奇偶性来确定获胜者。

 ## 算法演练

 我们将问题重新表述为计算在系统达到不可能移动的状态之前存在多少有效减量操作。 

### 1. 构建值的频率

 我们计算$cnt[x]$，每个值出现的次数$x$在数组中。 只有出现在约束或数组中的值才重要。 

的作用$cnt$是确定哪些约束值已经饱和。 

### 2. 识别饱和约束点

 对于每个约束$x \to limit_x$，我们检查是否$cnt[x] = limit_x$。 如果等式成立，那么$x$立即饱和。 

这样的数值$x$成为永久的障碍，因为任何试图将值从$x+1$进入$x$是被禁止的。 

### 3. 对饱和点进行排序

 我们收集所有饱和值并逐渐对它们进行排序。 这些点将整数线分割成独立的线段。 

两个连续饱和值之间$b < c$，值为$(b, c]$只能向下移动，直到到达$b$。 

### 4. 定义每个值的有效下限

 对于每个值$v$， 定义$L(v)$作为最大饱和值$\le v$。 如果不存在的话，$L(v) = 0$。 

该值是任何元素开始的最低级别$v$可以达到。 

### 5. 计算总移动次数

 每个元素从 value 开始$v$可以精确地递减$v - L(v)$在它被卡住之前的次数。 

我们将所有元素的贡献相加：$$\text{moves} = \sum_{i=1}^{n} (a_i - L(a_i)).$$### 6. 按平局判定胜负

 每一步都会翻转回合。 做出最后一步的玩家获胜。 因此：

 - 如果总步数为奇数，则 Pico 获胜。 
- 如果是的话，FuuFuu 获胜。 

### 为什么它有效

 一旦一个值变得饱和，它就永远不能增加，并且没有元素可以通过它。 这创建了划分状态空间的不可变边界。 在每个分区内，每次移动都会严格减少总“到边界的距离”，并且任何移动都不能跨越分区。 因此，每次有效的移动都恰好对应于减少总距离$\sum (a_i - L(a_i))$经过$1$，并且没有任何替代的移动顺序可以改变这个总数。 这使得游戏相当于正常游戏下的单堆该大小的游戏，其中最佳结果仅取决于奇偶校验。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

T = int(input())
for _ in range(T):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    cnt = {}
    for v in a:
        cnt[v] = cnt.get(v, 0) + 1

    limit = {}
    saturated = set()

    for _ in range(k):
        x, y = map(int, input().split())
        limit[x] = y

    for x, y in limit.items():
        if cnt.get(x, 0) == y:
            saturated.add(x)

    sat = sorted(saturated)

    def floor(v):
        # largest saturated value <= v
        lo, hi = 0, len(sat)
        while lo < hi:
            mid = (lo + hi) // 2
            if sat[mid] <= v:
                lo = mid + 1
            else:
                hi = mid
        return sat[lo - 1] if lo > 0 else 0

    total = 0
    for v in a:
        total += v - floor(v)

    if total % 2:
        print("Pico")
    else:
        print("FuuFuu")
```该实现首先构建频率计数，然后识别饱和约束点。 对排序的饱和列表进行二分搜索计算每个值的有效下限。 最终的总和是强制递减的数量的总和。 

关键的实施细节是，只有平等的情况才会产生障碍； 严格的不平等并不限制未来的行动。 

## 工作示例

 ### 示例 1

 输入：```
n = 3, k = 0
a = [1, 2, 3]
```| 步骤| 行动| 结果 |
 | ---| ---| ---|
 | 1 | 没有限制| 无饱和点|
 | 2 | 对于所有 v | 楼层(v)=0 |
 | 3 | 计算总和 |$1+2+3=6$|

 总步数 = 6，偶数，所以 FuuFuu 获胜。 

这符合这样一个事实：游戏只是一个简单的倒计时到零，没有任何限制。 

### 示例 2

 输入：```
n = 3, k = 1
a = [1, 2, 2]
constraint: 0 -> 1
```| 步骤| 行动| 结果 |
 | ---| ---| ---|
 | 1 | cnt[0]=1 等于限制 | 0 饱和 |
 | 2 | 饱和 = {0} | |
 | 3 | 对于所有 v | 楼层(v)=0 |
 | 4 | 总计 = 1+2+2 = 5 | |

 总步数 = 5，奇数，因此 Pico 获胜。 

0 处的饱和值在这里不会造成任何阻碍，但它仍然定义了系统的边界。

                sat.append(x)
        sat.sort()

 ## 边缘情况

 当约束值在开始时已经完全饱和时，就会出现关键的边缘情况。 在这种情况下，它立即成为永久的边界。 例如，如果所有出现的$0$已经达到$limit_0$，则没有值$1$或更高的可以移入$0$，冻结此时的结构。 该算法可以正确处理此问题，因为这些值在计算楼层之前已显式插入到饱和集中。 

另一种边缘情况是不存在约束的情况。 那么不存在饱和点，每一层都是$0$，结果简化为所有元素总和的奇偶性。
