 ## 解决方案
 # 问题理解

 我们有一棵有根的树。 每个节点都有一个有序的子节点列表。 语句中的程序不再进行正常的深度优先遍历：在一个节点完成其所有子节点之后，它将该节点从另一端放回到列表中。 任务是确定在结果无限序列中几个极大位置打印的值。 

输入描述以节点 1 作为根的树。 对于每个节点，我们都知道将按顺序访问的子节点。 在树描述之后，每个查询给出无限输出序列中的位置。 查询的答案是打印在该位置的节点号。 

困难的部分不是树的大小。 该树只有 50 个节点，因此即使二次预处理也是无害的。 然而，位置最多可以有 100 个数字，这排除了在到达查询位置之前生成序列的可能性。 我们需要在流程本身中找到重复结构。 

粗心的实施可能会在几个小细节上失败。 单节点树就是一个很好的例子。```
Input
1 3
0
1
2
100000000000000000000
```输出是：```
1
1
1
```假设每个节点最终都会移动到不同节点的解决方案将会失败，因为叶子会重复调度自身。 

另一个常见的错误是仅模拟打印的节点而不是完整的双端队列。 例如：```
Input
2 5
1 2
0
1
2
3
4
5
```输出是：```
1
2
1
2
1
```下一个打印的节点取决于存储在双端队列中的挂起状态，而不仅仅是前一个打印的值。 忘记内部状态会产生错误的循环。 

# 方法

 最直接的方法是直接模拟程序。 我们保留双端队列`(node, child_index)`，执行精确的操作，并记录每个打印的节点。 这是正确的，因为它实际上是原始程序。 当查询要求诸如位置之类的内容时，就会出现问题`10^100`; 模拟将需要不可能数量的操作。 

有用的观察结果是该程序没有无限的内存。 影响未来的唯一信息是当前双端队列内容。 双端队列的状态仅由描述节点和子位置的对组成。 由于树最多有 50 个节点，因此只有少量可能的对类型。 该过程是确定性的：相同的双端队列状态将始终产生相同的下一个状态和相同的未来输出。 

蛮力之所以有效，是因为每个转换都很容易模拟，但由于序列长度巨大而失败。 双端队列状态最终重复的观察让我们可以将问题简化为在确定性状态机中寻找循环。 一旦知道了循环，每个巨大的查询就可以映射到该循环内的相应位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(位置) | O(n) | 太慢了 |
 | 最佳 | O(C + k) | O(C + k) | O(C)| 已接受 |

 这里`C`是重复之前达到的不同双端队列配置的数量。 在给定的限制下，这个值很小。 

# 算法演练

 1. 将当前程序状态存储为双端队列`(node, next_child_index)`。 从单对开始`(1, 0)`。 在每个模拟步骤之前，使用整个双端队列作为循环检测的关键，因为两个相等的双端队列将生成相同的 future。 
2. 虽然当前的双端队列状态以前没有出现过，但请记住它在生成的序列中的位置。 从右侧删除元素，将其节点编号附加到答案序列中，并执行与原始程序完全相同的双端队列更新。 
3. 当出现之前看到的双端队列状态时，将生成的序列拆分为前缀和重复循环。 该双端队列状态的第一次出现标志着循环的开始。 
4. 对于每个查询位置，如果该位置在其中，则直接使用前缀。 否则，减去循环起点并使用循环长度取模来找到循环中的等效位置。 

这样做的原因是双端队列转换的确定性本质。 双端队列配置包含确定每个未来操作所需的所有信息。 一旦相同的配置出现两次，未来配置和打印节点的顺序必须永远重复。 

# Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    children = [[] for _ in range(n + 1)]
    for i in range(1, n + 1):
        data = list(map(int, input().split()))
        children[i] = data[1:]

    queries = [input().strip() for _ in range(k)]

    q = deque()
    q.append((1, 0))

    seen = {}
    order = []

    while True:
        state = tuple(q)
        if state in seen:
            cycle_start = seen[state]
            break

        seen[state] = len(order)

        node, idx = q.pop()
        order.append(node)

        if idx != len(children[node]):
            q.append((node, idx + 1))
            q.append((children[node][idx], 0))
        else:
            q.appendleft((node, 0))

    cycle_len = len(order) - cycle_start

    ans = []
    for s in queries:
        pos = int(s) - 1
        if pos < len(order):
            ans.append(str(order[pos]))
        else:
            pos = cycle_start + (pos - cycle_start) % cycle_len
            ans.append(str(order[pos]))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```代码中的双端队列与原程序的结构相同。 一对被删除`pop()`因为原来的程序使用`pop_right`。 两个可能的更新被直接复制：未完成的节点推送它们的延续，然后推送它们的下一个子节点，而完成的节点则插入到左侧。 

元组转换是重要的实现细节。 可变双端队列不能用作字典键，因此当前内容将转换为不可变元组。 Python 整数会自动处理 100 位查询值，因此不需要特殊的大整数处理。 

循环映射内部使用从零开始的索引。 首先将查询减一，然后将前缀之外的位置包装在循环内。 这可以避免在循环的第一个元素周围出现相差一个的错误。

 # 边缘情况

 对于单节点树，唯一的双端队列状态是`(1,0)`。 每一步都会打印节点 1 并将相同的状态放回到双端队列中。 循环长度为一，因此每个查询都映射到相同的值。 

对于一个节点有多个子节点的树，该算法不会假设子节点在被访问后消失。 每个延续对都保留在双端队列中，直到被处理。 这就是为什么存储完整的双端队列状态而不是仅存储当前节点。 

对于非常大的查询值，该算法从不尝试计数到请求的位置。 一旦知道周期开始和长度，诸如`10^100`使用除法和对循环长度取模来减少，在序列的重复部分中产生相同的位置。
