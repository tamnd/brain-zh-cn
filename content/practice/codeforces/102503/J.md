 ## 解决方案
 ## 问题理解

 这些岛屿和桥梁形成了一个相连的无向多重图。 甘地希望在保持图表连通的同时移除尽可能多的桥梁。 删除最大数量的桥意味着剩余的图必须恰好包含连接所需的最小数量的边，因此剩余的桥形成生成树。 

在所有可能的生成树中，只有文化值之和最大的生成树才是有效的。 对于每个查询，我们都会得到一组桥索引，并且必须计算这些桥中有多少个出现在至少一个最佳生成树中。 

输入大小排除了尝试显式构建生成树的可能性。 该图可以包含大约 133000 个桥，因此即使接近二次的算法也是不可能的。 我们需要一个基于排序和近线性图处理的解决方案。 

棘手的案件来自平等的文化价值观。 如果所有值都不同，则最大生成树将是唯一的，但相同的值可以创建许多有效的树。 另一个常见的错误是将克鲁斯卡尔运行中选择的每一条边视为唯一可能的答案。 该查询询问边是否可以出现在任何最大生成树中。 

例如：```
1
3 3
1 2 5
2 3 5
1 3 5
1
3 1 2 3
```答案是：```
3
```使用一次 Kruskal 运行的粗心实现将仅保留两条边并错误地回答 2。由于所有边具有相等的值，因此任何两条边形成最大生成树，因此每条边都是可能的。 

## 方法

 强力解决方案可以枚举所有生成树，计算它们的文化值，保留最大值，然后针对所有最佳树测试每个查询边缘。 这是正确的，因为它直接检查定义，但生成树的数量可以是指数级的。 即使仅生成边的子集也会给出大约 (2^b) 种可能性，这对于最大的图来说已经是不可能的。 

有用的观察是最大生成树具有贪婪结构。 Kruskal 的算法将边缘从较大的文化值处理为较小的文化值。 对于一种文化值，具有较大值的边缘已被修复。 在收缩由较大边形成的分量之后，连接两个不同分量的当前值的每条边都可以包含在某个最优生成树中。 端点已连接的边永远不会出现，因为已经存在更好的循环连接。 

因此，问题就变成了找到克鲁斯卡尔算法允许的每一条边，然后通过计算允许的索引来回答查询。

 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 | O(b log b) | O(b log b) | O(n + b) | 已接受 |

 ## 算法演练

 1. 按文化价值递减对所有桥梁进行排序。 最大生成树使用与 Kruskal 相同的贪婪排序，但首先使用最大的权重。 
2. 维护一个不相交的集合联合结构，其中包含由所有先前处理的较大文化值创建的连接组件。 
3. 在具有相同文化价值观的群体中建立桥梁。 对于组中的每个网桥，检查其两个端点当前是否属于不同的 DSU 组件。 如果他们这样做，请尽可能标记桥梁。 原因是在这个等值层内，任何非循环边都可以被选择作为生成森林的一部分。 
4. 检查整个组后，合并该组中连接不同当前组件的桥的所有端点。 这些合并代表在转向较小的值之前将这种文化值添加到结构中。 
5. 对于每个查询，尽可能计算有多少列出的桥索引被标记。 

工作原理：DSU 始终代表已通过严格的更大文化价值观连接起来的组件。 以自身权重连接两个不同分量的边可以替代某些最大生成树中相同权重的另一条边，因此它属于至少一个最优解。 一个 DSU 组件内的边将使用不更差的边创建一个循环，因此包含它不能改进生成树，并且任何优化都不需要它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n + 1))

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a != b:
            self.p[b] = a

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, b = map(int, input().split())
        edges = []

        for i in range(1, b + 1):
            x, y, c = map(int, input().split())
            edges.append((c, x, y, i))

        edges.sort(reverse=True)

        possible = [False] * (b + 1)
        dsu = DSU(n)

        i = 0
        while i < b:
            j = i
            while j < b and edges[j][0] == edges[i][0]:
                j += 1

            for k in range(i, j):
                _, x, y, idx = edges[k]
                if dsu.find(x) != dsu.find(y):
                    possible[idx] = True

            for k in range(i, j):
                _, x, y, _ = edges[k]
                dsu.union(x, y)

            i = j

        q = int(input())
        for _ in range(q):
            data = list(map(int, input().split()))
            cnt = 0
            for idx in data[1:]:
                if possible[idx]:
                    cnt += 1
            ans.append(str(cnt))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```排序步骤将相等的区域性值分组在一起，因为一次处理一条边会错误地允许相等权重的边影响同一组中的另一条边。 

DSU 合并在标记整个组后发生。 此顺序是主要的实现细节。 如果立即进行合并，则具有相同区域性值的后续边缘可能会错误地显示为被阻止。 

数组`possible`存储问题的图形部分的答案。 由于所有查询的总大小受到桥数量的限制，因此每个查询可以简单地扫描其列出的边。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(b log b) | O(b log b) | 排序占主导地位，而 DSU 操作几乎是恒定的摊销时间 |
 | 空间| O(n + b) | 存储边、DSU 父项和可能的标志 |

 限制允许大约 133000 个桥，因此排序加上 DSU 处理很容易满足时间限制。 

## 工作示例

 对于样本：```
4 4
1 3 40
3 4 20
1 2 30
2 4 10
```这些桥梁已经按照文化排序了。 

| 步骤| 当前边缘 | DSU 状态 | 可能 |
 | --- | --- | --- | --- |
 | 40 | 40 1-3 | 1-3 {1,3} 合并 | 边缘 1 |
 | 30| 1-2 | 1-2 {1,2,3} 合并 | 边缘 3 |
 | 20 | 3-4 | 3-4 {1,2,3,4} 合并 | 边缘 2 |
 | 10 | 10 2-4 | 2-4 相同的组件 | 没有|

 有效的桥为 1、2 和 3。第一个查询包含边 2 和 4，因此只有边 2 是可能的，答案为 1。第二个查询包含边 2 和 3，两者都可能，因此答案为 2。 

## 边缘情况

 自环会被自动拒绝，因为两个端点始终具有相同的 DSU 代表。 

并行桥可以正确处理，因为桥是通过其索引而不是端点来识别的。 连接同一岛屿的两座桥梁，如果文化价值观不同，可能会有不同的答案。 

每座桥梁都具有相同文化价值的图表也可以正确处理。 第一个 DSU 遍尽可能查看不同组件之间的每条边，这与每条边都可以属于某个生成树的事实相匹配。
