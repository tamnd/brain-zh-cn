 ## 解决方案
 ## 问题理解

 菜肴名称是通过连接三个可能的部分来构建的：`TJ`,`si`， 和`log`。 每出现一件就代表一份其相应成分。 这些片段混合在一起，没有分隔符，任务是恢复这三个片段各自出现了多少次。 

输入给出了几个菜名。 每个名称都有其长度，但长度仅作为输入元数据存在，因为字符串本身包含所需的所有信息。 对于每个名称，输出必须按顺序包含三个计数`TJ`,`si`， 和`log`。 

所有菜名的总长度最多为 100000。这意味着算法应该只处理每个字符恒定的次数。 在最坏的情况下，二次方法将执行大约 100000² 次操作，这远远超出了所需的范围，并且在时间限制内也不太适合。 线性扫描就足够了，因为每个字符都属于三个有效片段之一。 

主要的边缘情况来自于碎片具有不同的长度。 粗心的解决方案可能会计算字符而不是标记，或者假设每个小写段具有相同的大小。 

例如：```
1
TJTJ
```正确的输出是：```
2 0 0
```计算数量`T`字符或将每两个字符视为令牌在这里意外地起作用，但是一旦`si`和`log`出现。 

另一种情况是：```
1
silog
```正确的输出是：```
0 1 1
```搜索的解决方案`log`第一个并跳过三个字符可能会错误地错过`si`如果它没有保持正确的扫描位置。 

最后一种边界情况是仅包含一个标记的名称：```
1
log
```正确的输出是：```
0 0 1
```该实现必须处理短字符串，而不尝试读取超出末尾的字符。 

## 方法

 最简单的方法是反复查找字符串中的已知片段并将其删除。 由于保证字符串是有效的，我们总是可以找到分解为`TJ`,`si`， 和`log`。 这种方法是正确的，因为每移除一块就对应一份。 

这种方法的问题是重复搜索和重建剩余的字符串。 如果字符串的长度为 100000，则在最坏的情况下重复扫描其中的大部分可能会导致大约 100000 × 100000 次操作，即大约 100 亿个字符检查。 那是不必要的。 

关键的观察结果是字符串已经被排列为有效片段的序列。 我们不需要找到这些碎片在全球范围内的位置。 我们只需要在从左向右移动的过程中决定当前的棋子即可。 第一个字符完全决定了令牌类型。 一个`T`必须开始一个`TJ`，而小写字符开始`si`或者`log`。 在小写标记中，第二个字符将它们区分开来，因为`si`开始于`s`和`log`开始于`l`。 

暴力破解之所以有效，是因为每次有效的分解都会给出相同的计数，但它会失败，因为它不断重新发现单次扫描可以立即识别的位置。 观察到每个标记都有一个独特的起始模式，我们可以将整个任务简化为线性解析器。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从菜名的第一个字符开始，从左向右移动。 维护三个计数器`TJ`,`si`， 和`log`。 
2.如果当前字符是`T`, 数一`TJ`并将指数向前移动两个位置。 有效性保证意味着下一个字符必须是`J`。 
3. 如果当前字符是`s`, 数一`si`并将指数向前移动两个位置。 下一个字符必须是`i`，因此令牌已完全消耗。 
4. 如果当前字符是`l`, 数一`log`并将指数向前移动三个位置。 接下来的两个字符保证完成令牌。 
5. 扫描到达字符串末尾后，打印三个计数器。 

此解析有效的原因是没有两个有效标记共享相同的起始字符。 当扫描在剩余标记的开始处时，恰好存在一种可能的解释，因此不需要回溯或动态编程。 

为什么它有效：

 扫描期间的不变性是当前索引之前的每个字符都已被拆分为完整的标记并正确计数。 在每一步中，下一个令牌都由其第一个字符唯一标识，因此该算法恰好消耗一个有效令牌并恰好增加其相应的计数器。 由于保证输入是有效的菜肴名称，因此扫描会消耗整个字符串，使计数器等于每个成分标记出现的次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, s = input().split()

        tj = 0
        si = 0
        log = 0

        i = 0
        while i < len(s):
            if s[i] == 'T':
                tj += 1
                i += 2
            elif s[i] == 's':
                si += 1
                i += 2
            else:
                log += 1
                i += 3

        ans.append(f"{tj} {si} {log}")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```使用读取输入`sys.stdin.readline`因为可能有很多测试用例。 该函数独立处理每个字符串并在打印它们之前存储答案。 

三个计数器直接代表所需的输出值。 索引变量按已识别的标记的长度前进。 这是重要的实现细节，因为将其增加 1 会重复检查已经属于计数标记的字符。 

在读取令牌的下一个字符之前不需要进行边界检查，因为输入保证每个菜肴名称都是有效的。 在 Python 中，整数溢出不是问题，最大可能的计数器值只是字符串长度。

 ## 边缘情况

 对于输入：```
1
TJTJ
```算法从索引开始`0`，看到`T`，加一`TJ`计数器，并跳转到索引`2`。 它重复相同的动作并产生：```
2 0 0
```这处理仅由一种标记类型组成的字符串。 

对于输入：```
1
silog
```该算法首先看到`s`, 计数`si`，并移动到`l`特点。 然后就可以算了`log`。 结果是：```
0 1 1
```这证实了较短的标记可以立即出现在较长的标记之前，而不会产生歧义。 

对于输入：```
1
log
```算法输入`else`分支一次，增加`log`计数器，并移过所有三个字符。 输出是：```
0 0 1
```扫描从不尝试访问字符串之外的字符，因为索引完全按照已识别标记的大小移动。
