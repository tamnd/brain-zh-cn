 ## 解决方案
 ## 问题理解

 我们在数据中心中有一个矩形的灯网格。 每个单元要么亮，要么不亮。 更改配置的唯一方法是选择整行或整列，然后翻转其中的每个灯，将 0 变为 1，将 1 变为 0。 

目标是使用尽可能少的行和列翻转来使每盏灯点亮。 如果没有任何翻转序列可以实现完全照亮的网格，我们必须报告这一事实。 

每个操作同时影响整个行或列，这意味着决策的效果在整个网格中高度耦合。 翻转行会更改其中的所有列，翻转列会更改其中的所有行，因此最终状态仅取决于选择的行和列，而不取决于顺序。 

这些约束允许网格最多为 2500 x 2500。直接模拟翻转序列是不可能的，因为即使尝试行和列的所有子集，每个维度也已经有 2^2500 个选择的数量级。 即使简单地检查单个配置也会花费 O(nm)，因此任何方法都必须将决策空间减少到网格大小中线性或接近线性的程度。 

当网格结构对行和列施加矛盾的要求时，就会出现关键的边缘情况。 

例如，考虑 2 x 2 网格：```
0 1
1 0
```可以翻转第 1 行和第 2 行以获取所有行，但是如果忽略列交互，尝试逐行修复的粗心贪婪方法可能会陷入困境。 

另一个微妙的情况是当单个行或列强制奇偶校验约束不一致时。 例如：```
0 0 1
0 0 1
0 0 0
```在这种配置中，固定一行以匹配另一行可能会强制进行列翻转，从而撤消之前的工作，而贪婪地独立修复单元格的简单方法将发生振荡，而无法达到稳定的全一配置。 

这些示例强调，问题不在于单元格的局部校正，而在于找到行和列翻转的全局一致分配。 

## 方法

 蛮力视角就是对每一行每一列决定是否翻转。 如果我们将行翻转表示为数组 R，将列翻转表示为数组 C，每个数组都是二进制的，则单元格 (i, j) 处的最终值将成为原始值 XOR R[i] XOR C[j]。 我们希望每个单元格的值都等于 1。 

暴力解决方案会尝试所有 2^n 行选择和 2^m 列选择，并且对于每个选择验证所有单元格是否都变为 1。这在概念上是有效的，因为它直接匹配操作的定义，但当 n 和 m 达到甚至 20 时，它会立即失败，因为配置的数量爆炸超出了可行性。 

关键的观察结果是 XOR 中的条件是线性的。 一旦我们修复了第一行的翻转状态，每列翻转就会被强制。 每列 j 必须精确翻转，以便在应用列翻转后第 0 行变为全 1。 之后，每隔一行就没有自由了：要么匹配所需的模式，要么不一致。 

这将问题简化为仅隐式尝试第一行状态的两种可能性，或者更具体地说，使用第一行作为参考来确定列翻转，然后验证所有行的一致性。 整个网格崩溃成一个奇偶方程组。 

这种变换之所以有效，是因为每个单元都施加了 R[i] XOR C[j] = a[i][j] XOR 1 形式的约束，这是 GF(2) 上的线性系统。 一旦一个维度被锚定，另一个维度就会被确定。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 行和列的暴力子集 | O(2^(n+m) · nm) | O(2^(n+m) · nm) | O(1) | O(1) | 太慢了|
 | 行/列奇偶校验减少 | O(纳米) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将第一行视为锚点并从中导出列翻转。 

1. 假设最终的网格应该是全1。 对于每一列 j，确定是否必须翻转 j 列，使单元格 (0, j) 变为 1。这直接将 C[j] 固定为当前值与 1 之间的异或差。 
2. 确定列决策后，计算在不应用行翻转的情况下每行的外观。 对于第 i 行，我们可以在应用列翻转后推断它是否符合所需的全一条件。 
3. 对于每一行 i，检查是否存在使整行一致的单个二元选择 R[i]。 这意味着该行中的所有单元格必须就所需的行翻转值达成一致； 否则无法配置。 
4. 如果配置一致，计算需要翻转的行数，因为每个不一致的行都会违反可行性。 
5. 如果需要，使用互补假设重复相同的逻辑，并在有效配置中采取最少的翻转次数。 

逐行检查一致性的原因是，一旦列被固定，每一行就成为针对单个二进制变量 R[i] 的独立约束。 如果即使一行需要矛盾的值，则该列配置下不存在全局分配。 

### 为什么它有效

 每个单元方程简化为 R[i] XOR C[j] 等于从初始网格导出的固定目标值。 一旦 C 从第一行开始固定，每一行 i 都会产生一个方程组，所有方程组都定义相同的 R[i] 值。 如果该行中的任何两列与隐含的 R[i] 不一致，则系统无解。 否则该行已完全确定。 这保证了我们不会错过行和列之间的任何隐藏交互，因为所有交互都已经在 XOR 约束中进行了编码。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    def try_build():
        # compute column flips from first row
        col = [0] * m
        for j in range(m):
            col[j] = a[0][j] ^ 1

        # determine row flips
        row = [0] * n

        for i in range(n):
            # infer required row flip from first column
            row[i] = a[i][0] ^ col[0] ^ 1

            # verify consistency across row
            for j in range(m):
                if (a[i][j] ^ col[j] ^ row[i]) != 1:
                    return None

        return sum(row) + sum(col)

    ans = try_build()

    print(ans if ans is not None else -1)

if __name__ == "__main__":
    solve()
```该解决方案首先修复列翻转，以便在应用列操作后第一行完全变成行。 这会立即确定每列的唯一候选者。 然后，为每一行分配一个从一个参考列派生的翻转值，并针对所有列验证整行以确保不会出现矛盾。 

一个微妙的实现细节是行翻转源自单个列，但必须针对该行中的每一列进行检查。 缺少此检查会导致错误地接受不一致的配置。

 ## 边缘情况

 1 x 1 网格是最简单的应力情况，因为行和列都引用相同的单元格。 该算法正确计算第一行的单列翻转，然后验证行一致性，产生正确的单翻转要求。 

完全点亮的网格不需要有效的翻转。 列推导为翻转产生全零，行验证确认没有矛盾，从而导致零操作。 

只有一个单元格错误但破坏奇偶校验一致性的网格将在行验证期间失败。 导出的列翻转将在至少一行中强制产生矛盾，导致立即拒绝，这符合正确的不可能条件。 

一个典型的失败案例是网格看起来可以在本地修复，但行之间存在全局奇偶校验不匹配。 在这种情况下，第一行可能建议有效的列翻转，但另一行将在不同列之间产生冲突的行翻转要求，从而触发不一致检查并正确返回-1。
