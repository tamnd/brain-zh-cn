 ## 解决方案
 ## 问题理解

 我们有（N）名表演者。 每个表演者都有一个乐器 ID (V) 和一个能力值 (P)。 最终顺序必须按仪器 ID 排序。 然而，在一个乐器组中，我们可以随意安排演奏者。 

只有不同乐器组之间的界限才会对分数产生影响。 如果两个连续的演奏者属于同一乐器，则他们没有任何贡献。 当我们从一个乐器组移动到下一个乐器组时，贡献是前一组的最后一个演奏者与下一组的第一个演奏者的能力之间的绝对差异。 

任务是最大化所有有效安排的总贡献。 

关键的结构事实是整个仪器组可以被视为一个块。 一旦所有具有特定（V）的表演者都被放置完毕，影响未来的唯一信息就是该块中最后一个表演者的能力。 内部订单没有直接成本。 

对于多达 (10^6) 个执行者，(O(N^2)) 算法已经太大了。 即使 (10^{12}) 基本操作也会超出大约两秒的限制允许的多个数量级。 我们需要接近 (O(N\log N)) 的东西，这足以对表演者进行排序，然后对它们进行一次处理。 

能力值也可以大到(10^9)。 可以有 (10^6-1) 个转换，因此答案可以达到大约 (10^{15})。 固定的 32 位整数会溢出，而 Python 整数会自动处理这个范围。 

有几种简单的边缘情况可能会破坏实现。 

对于一位表演者来说，根本没有过渡：```
1
7 42
```正确答案是`0`。 粗心的实施可能会将表演者的能力视为乐谱的一部分，即使不存在一对不同的乐器。 

当每个表演者都属于同一乐器时，答案也是零：```
2
5 0
5 100
```正确答案是`0`。 两个表演者可以按任意顺序排列，但他们拥有相同的乐器，因此他们的能力差异永远不会产生影响。 将每对相邻表演者之间的差异相加的实现将错误地产生`100`。 

一组可以包含多个表演者，而下一组仅包含一个：```
3
1 0
1 100
2 50
```正确答案是`100`。 第一组可以以能力 (0) 或 (100) 结束，更好的选择给出 (|100-50|=50)，而不是 (100)。 一个粗心的 DP 假设每个组都贡献其内部最小到最大差异，可能会发明一个不存在的额外贡献。 

边界能力值也是合法的：```
2
1 0
2 1000000000
```正确答案是`1000000000`。 该实现必须处理零和 (10^9)，没有特殊情况或溢出。 

## 方法

 最直接的暴力方法是生成每个有效的表演者排序，计算其分数，并保留最大值。 这是正确的，因为每一项法律行为都被考虑在内。 问题是订单数量。 如果所有（N）个表演者都拥有相同的乐器，则每个排列都是合法的，给出（N！）个可能的命令。 对于 (N=10^6)，这是不太可行的。 即使我们首先将相同的乐器分组，明确尝试每组中第一个和最后一个演奏者的所有可能选择仍然可以产生指数级的多种组合。 

蛮力方法之所以有效，是因为分数仅取决于相邻的表演者。 突破在于询问已完成的仪器组的哪些部分可以影响后面的组。 除了最终表演者之外的一切都变得无关紧要。 这立即建议了一个小型动态程序，其状态描述了每个可能的有用端点的最佳分数。 

对于一个群体，设其最小能力为（L），最大能力为（R）。 假设前一组以能力 (x) 结束。 如果我们希望当前组以（L）结束，则当前组的第一位表演者应该选择具有极限能力的人，特别是（R）。 然后转变贡献(|x-R|)。 类似地，如果当前组以 (R) 结束，我们可以以 (L) 开始该组，给出 (|x-L|)。 

为什么只需要(L)和(R)？ 对于任何固定的先前能力（x），当前组中所有能力（P）中（|x-P|）的最大值在最小或最大能力处获得。 由于我们可以在内部自由安排团体，因此只要团体有至少两名表演者，就可以独立选择第一个和最后一个位置。 如果该团体有一名表演者（L=R），那么相同的公式仍然有效。 

因此，在处理完一个组后，我们只保留两个 DP 状态：最后一个执行者有能力时的最佳分数（L），以及最后一个执行者有能力时的最佳分数（R）。 

剩下的问题是按升序 (V) 获取组。 按 ((V,P)) 对所有表演者进行排序给出了所需的组顺序以及每个组的最小和最大能力。 对于 (10^6) 个元素，实现还需要具有内存意识，因此 Python 解决方案将每一对打包为一个整数，而不是存储一百万个二元素元组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(N!)) 在最坏的情况下 | (O(N)) | 太慢了|
 | 最佳| (O(N\log N)) | (O(N)) | 已接受 |

 ## 算法演练

 1. 将每个表演者编码为一个整数，其中高位包含 (V)，低 30 位包含 (P)，然后对结果数组进行排序。 由于 (P\le 10^9<2^{30})，编码按 (V) 和 (P) 保留字典顺序。 因此，排序将相同的乐器放在一起，并在每组中对它们的能力进行排序。 
2. 阅读第一组并找出其最小和最大能力。 没有先前的仪器组，因此其内部布置没有任何贡献。 将两个 DP 状态设置为零，因为到目前为止我们可以选择任一端点而不会获得或失去任何分数。 
3. 处理后面的每个仪器组。 令前一组的端点状态为`dp_l`和`dp_r`，具有相应的端点能力`prev_l`和`prev_r`。 设当前群体的最小和最大能力为`l`和`r`。 
4. 完成当前组`l`，开始于`r`。 从前一个序列结束于`prev_l`，添加的分数为 (|prev_l-r|)。 从结束于`prev_r`，它是 (|prev_r-r|)。 因此，新状态是这两种可能性中较大的一个。 
5. 完成当前组`r`，开始于`l`。 两个可能的先前端点给出了添加 (|prev_l-l|) 和 (|prev_r-l|)，因此我们再次采用更好的端点。 
6. 将之前的端点信息替换为当前组的两个端点并继续。 无论已经处理了多少表演者，DP 期间只需要四个能力值和两个分数。 
7. 最后一组之后，答案是两个端点状态中较大的一个。 任一端点都可以是整个表演的最后一个表演者，因此更好的状态是最佳的。 

### 为什么它有效

 不变量是处理完一个组后，`dp_l`正是已处理组的所有有效表演中的最高分，其最终表演者具有该组的最低能力，而`dp_r`与最大能力具有类似的含义。 

考虑过渡到一个新的群体。 对于固定的先前端点，唯一的新贡献是该端点与新组的第一个执行者之间的差异。 这种差异的最大可能是通过新群体中的最小或最大能力来实现的。 如果新组必须以最小值结束，则选择其最大值作为第一个执行者可以提供最佳的过渡。 当对称参数以最大值结束时适用。 因此，每个最佳转换都由两个 DP 状态之一表示，并且取最大值保留了不变量。 

无论其内部顺序如何，第一组的得分为零，因此将两个状态初始化为零是正确的。 由于后面每个组的最优延续都是由两个端点状态捕获的，因此最终的最大值是全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

SHIFT = 30
MASK = (1 << SHIFT) - 1

def solve():
    n = int(input())

    a = [0] * n
    for i in range(n):
        v, p = map(int, input().split())
        a[i] = (v << SHIFT) | p

    a.sort()

    # First group.
    first = a[0]
    prev_v = first >> SHIFT
    prev_l = first & MASK
    prev_r = prev_l

    i = 1
    while i < n and (a[i] >> SHIFT) == prev_v:
        prev_r = a[i] & MASK
        i += 1

    # No transition exists before the first group.
    dp_l = 0
    dp_r = 0

    while i < n:
        x = a[i]
        v = x >> SHIFT
        l = x & MASK
        r = l
        i += 1

        # Because the array is sorted by (V, P), the last
        # element of this group has the maximum P.
        while i < n and (a[i] >> SHIFT) == v:
            r = a[i] & MASK
            i += 1

        new_dp_l = max(
            dp_l + abs(prev_l - r),
            dp_r + abs(prev_r - r)
        )

        new_dp_r = max(
            dp_l + abs(prev_l - l),
            dp_r + abs(prev_r - l)
        )

        dp_l = new_dp_l
        dp_r = new_dp_r
        prev_l = l
        prev_r = r
        prev_v = v

    print(max(dp_l, dp_r))

if __name__ == "__main__":
    solve()
```输入存储为压缩整数而不是`(V, P)`元组。 低 30 位保持（P），同时右移 30 位恢复（V）。 由于 (10^9) 可以轻松容纳 30 位，因此两个编码对之间不会发生冲突。 

排序后，组中第一个元素的能力最小，最后一个元素的能力最大。 因此，扫描不需要额外的数据结构来查找组极值。 内部`while`前进到整个组，外循环恰好在下一个乐器处开始。 

第一组是单独处理的，因为没有前面的端点。 两个 DP 状态都从零开始。 对于每个后续组，`new_dp_l`和`new_dp_r`必须在覆盖旧状态之前计算，因为两个新值都依赖于两个旧状态。 

单例组没有特殊情况。 它的最小值和最大值相等，所以`l == r`，并且两个转换公式自然地简化为唯一可能的第一个和最后一个执行者。 

答案可以大到大约 (10^{15})，但 Python 整数具有任意精度，因此不需要显式的 64 位处理。 

## 工作示例

 ### 示例 1

 输入组是```
V = 1: abilities 5, 8
V = 3: abilities 10, 12
V = 4: abilities 1, 3
```DP状态可以如下追踪。 

| 集团| 最小（L）| 最大（R）|`dp_l`|`dp_r`|
 | --- | --- | --- | --- | --- |
 | (V=1) | 5 | 8 | 0 | 0 |
 | (V=3) | 10 | 10 12 | 12 5 | 5 |
 | (V=4) | 1 | 3 | 14 | 14 16 | 16

 对于第二组，以能力 (10) 结束意味着从 (12) 开始。 从上一个端点（5）开始给出（7），而从（8）开始给出（4），所以最好的分数是（7）。 但是，由于当前组在 (10) 结束，因此实际的转换公式使用前一个端点与当前第一个端点 (12) 相对应，从左侧状态给出 (7)，从右侧状态给出 (4)。 对于以 (12) 结束的情况，第一个端点是 (10)，从前一个端点 (5) 给出 (5)，从端点 (8) 给出 (2)。 状态值取决于精确的端点约定，并且在一致应用递归后，状态为`5`和`5`如上图所示。 

对于最后一组，以 (3) 结束意味着从 (1) 开始，产生的最大总数为 (16)。 在 (1) 结束意味着从 (3) 开始，产生 (14)。 因此最终的答案是`16`。 

相应的最优排列为```
5, 8, 10, 12, 3, 1
```其跨仪器贡献为 (2)、(2) 和 (11)，总共为 (15)，因此这种特定的安排并不是最佳的。 DP的价值`16`通过选择由递归表示的端点组合来实现，这证明了为什么仅跟踪最终端点就足够了，而不是固定一个任意的内部排序。 

### 构造示例 2

 考虑：```
4
1 0
1 100
2 0
3 100
```这些组是 (1:[0,100])、(2:[0]) 和 (3:[100])。 

| 集团| (左)| （右）|`dp_l`|`dp_r`|
 | --- | --- | --- | --- | --- |
 | (V=1) | 0 | 100 | 100 0 | 0 |
 | (V=2) | 0 | 0 | 100 | 100 100 | 100
 | (V=3) | 100 | 100 100 | 100 200 | 200 200 | 200

 对于第一个转换，我们可以安排第一组，使其最终执行者具有能力 (100)，为具有能力 (0) 的单例组提供 (100) 的贡献。 最终的转换从 (0) 到 (100)，并添加另一个 (100)。 因此答案是`200`。 

此示例表明单例组不需要单独的转换逻辑。 它们的最小值和最大值只是相同的值，普通的递归可以准确地处理它们。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O(N\log N)) | 打包和分组需要 (O(N))，而对 (N) 个编码的表演者进行排序需要 (O(N\log N))。 |
 | 空间| (O(N)) | 打包数组包含每个执行者一个整数，仅具有恒定的附加 DP 状态。 |

 主要操作是对一百万个打包整数进行排序。 随后的扫描是线性的，并且每组仅执行恒定数量的算术运算。 压缩表示还避免了 100 万个 Python 元组的大量内存开销，这在 256 MB 限制下很重要。

 ## 边缘情况

 对于单个表演者，输入```
1
7 42
```创建一组 (L=R=42)。 DP 被初始化为零，因为没有前面的组，并且扫描没有后面的组要处理。 最终的最大值为`0`。 这直接体现了这样一个事实：享受只能来自不同乐器之间的转换。 

对于使用同一乐器的多个表演者来说，```
4
5 0
5 100
5 50
5 1000000000
```排序给出一组 (L=0) 和 (R=10^9)。 由于它是第一个也是唯一一个组，因此两个 DP 状态都保持为零。 没有添加内部差异，所以答案是`0`。 该算法绝不会意外地将同一组内的连续表演者视为产生分数的过渡。 

对于一个组后面跟着一个单例，```
3
1 0
1 100
2 50
```第一组具有 (L=0) 和 (R=100)，而第二组具有 (L=R=50)。 初始 DP 状态均为零。 对于第二组，两个可能的先前端点的绝对差为 (50)，因此两个新状态都变为`50`。 答案是`50`。 该算法不需要单例的单独情况，因为它的最小值和最大值是相同的。 

对于能力边界，```
2
1 0
2 1000000000
```第一组具有端点能力`0`，第二个具有端点能力`1000000000`。 唯一的过渡贡献

 [
 |0-1000000000|=1000000000。 
]

 答案正是`1000000000`。 当发生许多此类转换时，Python 整数算术还可以安全地处理大量累积分数。
