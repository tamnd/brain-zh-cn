 ## 解决方案
 ## 问题理解

 我们需要找到同时被除数的每个正整数`a`和多个`b`。 输入给出两个整数`a`和`b`， 和`b <= a`并且两者都可能大到`10^12`。 输出应包含满足这两个条件的所有整数，按从小到大排列。 如果不存在这样的整数，则所需的输出只是一个空行。 

这两个条件以一种有用的方式相互作用。 假设一个有效数字是`x`。 自从`x`是的倍数`b`，我们可以写`x = b * k`对于某个正整数`k`。 自从`x`还必须分`a`，我们有`b * k | a`。 只有当`b`本身分裂`a`。 什么时候`b | a`， 写`a = b * n`。 然后`b * k | b * n`恰好在什么时候`k | n`。 因此，原来的问题被简化为找到所有约数`k`的`n = a / b`，然后将它们乘以`b`。 

的上限`10^12`排除任何扫描所有整数的方法`a`。 在最坏的情况下，这样的扫描执行大约`10^12`迭代次数，远远超出了两秒限制所能支持的范围。 即使只扫描多个`b`还不够，因为`b`可以是`1`，留下尽可能多的`10^12`候选人。 除数结构让我们通过对除数进行枚举直到平方根来做得更好。 由于相关值最多为`10^12`，其平方根最多为`10^6`，这很容易管理。 

有几种边缘情况，粗心的实现可能会处理不当。 如果`b`不分开`a`，没有答案。 例如，使用输入`10 3`, 没有倍数`3`可以分`10`，所以正确的输出是空的。 一个简单地生成倍数的实现`3`并停在`10`会产生`3 6 9`，即使这些数字都不能整除`10`。 

当出现第二种边缘情况时`a = b`。 用于输入`5 5`，唯一有效的数字是`5`， 因为`5`划分`5`并且是的倍数`5`。 减少后`b`，我们得到`n = 1`，其唯一除数是`1`。 对应的答案是`5 * 1 = 5`。 

第三种边缘情况是完美的正方形。 用于输入`36 2`，我们有`n = 18`, 而对于输入`49 7`，我们有`n = 7`。 更一般地说，如果`n`本身是一个正方形，发现的除数对`sqrt(n)`包含相同除数两次。 实现必须避免将该值添加两次。 例如，`a = 36, b = 1`有约数包括`6`， 但`6`在输出中只能出现一次。 

## 方法

 最直接的暴力解决方案是检查每个可能的整数`1`通过`a`，检查它是否可以被整除`b`和除数`a`。 我们可以通过仅检查多个`b`，但在最坏的情况下`b = 1`，所以我们仍然执行`10^12`检查。 即使每次检查都是恒定时间，这也远远超出了可用时间。 暴力法是正确的，因为每一个可能的答案都会被检查，但它的操作次数是根本问题。 

关键的观察是每个答案都包含`b`作为一个因素。 如果`b`不分开`a`，不可能有任何答案。 如果`b`划分`a`， 放`n = a / b`。 每个答案都有形式`b * k`，整除条件变为`k | n`。 我们将问题从寻找特殊约数转变为`a`找出较小数的每个普通约数`n`。 

除数可以成对枚举。 每当`i`划分`n`, 数量`n / i`也是一个除数。 我们只需要测试`i`最多`sqrt(n)`，因为每个大于平方根的除数都与小于平方根的除数配对。 因此我们最多执行`10^6`可分性检查。 我们收集每个除数对的两个成员，将它们乘以`b`，对结果值进行排序，然后打印它们。 

蛮力方法之所以有效，是因为它会检查可能答案的整个范围，但当该范围达到该范围时就会失败`10^12`。 观察到每个有效数字都是`b`乘以除数`a / b`将搜索空间减少到仅`O(sqrt(a / b))`候选人。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 最坏情况下的 O(a) | O(1) 不包括输出 | 太慢了 |
 | 最佳| O(sqrt(a / b) + d log d) | O(d) | 已接受 |

 这里`d`是的约数`a / b`。 对于最多的数字`10^12`,`d`与原来的搜索范围相比较小。 

## 算法演练

 1. 阅读`a`和`b`。 在进行任何除数枚举之前，检查是否`a % b`为零。 如果不是，则打印一个空行并停止，因为一个数字是`b`不能分开`a`除非`b`本身分裂`a`。 
2. 计算`n = a // b`。 现在每个有效答案都是准确的`b * k`， 在哪里`k`是一个除数`n`。 这是从`a = b * n`和`b * k | b * n`，这相当于`k | n`。 
3. 从一个空的答案列表开始并迭代`i`从`1`尽管`i * i <= n`。 仅测试此范围就足够了，因为低于平方根的每个除数在其上方都有一个配对除数。 
4. 每当`n % i == 0`， 添加`b * i`到答案列表。 还添加`b * (n // i)`，它是除数对的另一个成员。 
5. 如果`i * i == n`，不要单独添加第二个值。 在那种情况下`i`和`n // i`是相同的除数，因此将两者相加会重复一个答案。 
6. 对收集到的答案进行排序。 对于每对中的小成员，按升序发现除数，但它们配对的大成员不是全局排序的，因此排序给出了所需的数字顺序。 
7. 打印答案，并用空格分隔。 如果列表为空，则打印连接的字符串自然会产生所需的空行。 

### 为什么它有效

 经过整除性检查后，我们知道`a = b * n`。 一个数字`x`当它可以写成时，它就是一个有效的答案`x = b * k`和`x | a`。 替换这些表达式给出`b * k | b * n`，这相当于`k | n`。 因此，有效答案和除数之间存在一一对应的关系`n`，每个除数`k`映射到`b * k`。 

除数枚举检查每个`i <= sqrt(n)`。 如果`i`划分`n`，它的配对除数`n / i`也被发现，所以每个除数要么作为一对的小成员要么作为大成员生成。 方形情况是单独处理的，因此除数等于`sqrt(n)`恰好出现一次。 因此，乘以之后`b`和排序，输出只包含每个有效整数一次，并且不包含无效整数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())

    if a % b != 0:
        print()
        return

    n = a // b
    ans = []

    i = 1
    while i * i <= n:
        if n % i == 0:
            ans.append(b * i)

            other = n // i
            if other != i:
                ans.append(b * other)

        i += 1

    ans.sort()
    print(*ans)

if __name__ == "__main__":
    solve()
```第一个条件检查必要的整除性`a`经过`b`。 没有它，就没有理由搜索除数，因为每个候选人都必须包含`b`作为一个因素。 

变量`n`是缩小的问题规模，`a / b`。 该循环测试可能的小除数`1`通过`sqrt(n)`。 条件`i * i <= n`避免浮点平方根并且对于 Python 的任意精度整数是安全的。 

什么时候`i`划分`n`， 两个都`i`和`n // i`是除数。 将每个乘以`b`将它们转换回原始问题所需的实际数字。 这`other != i`检查处理完全平方数，防止平方根被插入两次。 

最后的排序是必要的，因为除数对是以混合顺序发现的。 例如，当`n = 12`，迭代发现`1, 12`， 然后`2, 6`， 然后`3, 4`。 这个特定的序列恰好是近乎有序的，但一般来说，转换后的值不需要以所需的全局顺序到达。 排序使输出条件变得明确。 

Python 整数不会溢出，因此诸如`b * (n // i)`即使它们有那么大也是安全的`10^12`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(sqrt(a / b) + d log d) | 我们测试除数`sqrt(a / b)`， 产生`d`答案，然后对它们进行排序。 |
 | 空间| O(d) | 答案列表存储有效值。 |

 自从`a / b <= 10^12`，除数搜索最多执行约`10^6`循环迭代。 除数的个数`d`远小于`10^6`，因此排序成本也适中。 该算法很好地满足了两秒的时间限制，并且很好地保持在 64 MB 内存限制之内。

 ## 边缘情况

 当`b`不分开`a`，算法在除数枚举之前退出。 用于输入`10 3`，第一个计算是`10 % 3 = 1`，因此答案列表保持为空，并且程序打印一个空行。 这可以防止处理每个倍数的常见错误`b`作为答案而不检查它是否真的可以除`a`。 

什么时候`a = b`，减少后的值为`n = 1`。 用于输入`5 5`，循环开始于`i = 1`， 和`1 * 1 <= 1`是真的。 自从`1`划分`1`，算法添加`5 * 1 = 5`。 配对除数也是`1`， 所以`other != i`为 false 并且不插入重复项。 然后循环结束，产生`5`。 

什么时候`n`是一个完美的正方形，重复的守卫是必不可少的。 考虑`36 1`。 相关减少数为`36`，以及当`i = 6`，两个除数表达式给出`6`。 该算法添加`6`一次并跳过第二次插入，因为`other == i`。 完整排序的输出是`1 2 3 4 6 9 12 18 36`。 

以尽可能大的值，例如`1000000000000 1000000000000`, 减少的数量仅为`1`。 该算法不会在附近任何地方循环`10^12`次。 它执行单个除数检查并输出原始值。 这说明了为什么通过以下方式减少问题`b`即使在应用平方根除数枚举之前也是有用的。
