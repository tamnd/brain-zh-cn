 ## 解决方案
 ## 问题理解

 Samuelo 的文本是一个字符串`s`，而 Roppa 猜测的隐藏信息是另一个字符串`t`。 如果我们可以删除一些字符，则认为猜测是正确的`s`同时保持剩余字符的原始顺序并准确地获得`t`。 换句话说，`t`必须是一个子序列`s`。 

例如，在`threeyellowfurryfiends`，需要的字符`hellofriend`尽管它们之间出现了许多不相关的字符，但它们以正确的顺序出现。 我们只关心相对顺序，而不关心连续位置。 

两个字符串最多可以包含`10^6`人物。 该大小排除了任何在二次循环中重复检查位置对的方法。 拥有一百万个字符，`O(nm)`算法最多可以执行`10^12`操作，远远超出了1秒的限制所能容纳的。 预期的解决方案必须基本上处理字符串一次，并在其总长度中给出线性时间。 内存限制也使得`O(nm)`动态编程表不切实际，因为一百万乘一百万条目将需要大量内存。 

一些边缘情况很容易被错误处理。 首先，两个字符串可以具有相同的长度。 例如，```
abc
abc
```有答案`YES`，因为必须使用每个字符并且字符串是相同的。 在最后一次匹配后意外需要未使用字符的实现可能会错误地返回`NO`。 

猜测也可能比原文更长。 例如，```
ab
abc
```有答案`NO`。 中的字符数不足`s`形成`t`。 一个粗心的实现，只检查每个字符是否`t`发生在某处`s`，如果不尊重多样性和顺序，可能会出错。 

重复的字符是另一个常见的错误来源。 为了```
aab
aaa
```答案是`NO`， 因为`s`仅包含两个`a`人物。 只是检查信件是否`a`看来还不够。 

最后，匹配的字符可以用任意文本分隔。 为了```
axbycz
abc
```答案是`YES`。 字符不需要相邻，因此搜索的实现`t`因为连续的子字符串会错误地拒绝它。 

## 方法

 一种直接但不必要的昂贵方法是构建动态编程表。 让`dp[i][j]`描述是否是第一个`j`的字符`t`可以作为第一个的子序列获得`i`的字符`s`。 对于每对`(i, j)`，我们决定是否忽略`s[i - 1]`，或者，当字符匹配时，将其用作下一个字符`t`。 这是正确的，因为每个可能的子序列要么使用当前字符，要么不使用。 

问题在于州的数量。 大致有`n * m`对，其中`n = len(s)`和`m = len(t)`。 在最大极限下，大约是`10^12`州。 在内存限制下，即使存储这样的表也是不可能的，并且计算它也太慢了。 

删除整个表的观察结果是，我们不需要记住所有可能的方式来匹配前缀`t`。 假设我们当前正在寻找角色`t[j]`。 在所有职位中`s`在可以匹配该字符的情况下，采取最早的可能位置总是至少与采取较晚的位置一样好。 较早的匹配至少留下与其余字符串一样多的剩余字符串`t`。 

这给出了贪婪扫描。 我们处理`s`从左到右，同时保持指向下一个字符的指针`t`我们需要的。 每当当前字符`s`匹配该目标字符，我们使用它并推进目标指针。 如果目标指针到达末尾`t`，整个猜测已成功嵌入。 如果`s`首先结束，不存在有效的嵌入。 

暴力DP之所以有效，是因为它明确地考虑了每个前缀组合，但由于组合太多而失败。 贪心观察让我们只保留当前目标角色的最早可行位置，将问题简化为一次遍历`s`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力DP | O(纳米) | O(纳米) | 太慢且内存太多|
 | 最优贪婪扫描| O(n + m) | O(1) 辅助空间 | 已接受 |

 ## 算法演练

 1. 阅读`s`和`t`，然后创建一个指针`j`最初等于零。 指针代表第一个字符`t`尚未匹配。 
2. 扫描每个字符`c`的`s`从左到右。 如果`j`还在里面`t`和`c == t[j]`，使用这个出现`c`匹配下一个所需的字符和增量`j`。 
3.如果`j`变得等于`len(t)`, 的每个字符`t`已匹配越来越多的位置`s`，所以答案是`YES`。 我们可以立即停止，因为没有其他字符相关。 
4. 如果扫描到达末尾`s`尽管`j < len(t)`，在之前的匹配之后至少没有找到一个所需的字符。 答案是`NO`。 

贪婪的选择是安全的，因为当`s[i] == t[j]`，使用位置`i`没有比跳过它并使用稍后出现的相同字符更糟糕的了。 其余的`t`只能从拥有更多职位中受益`s`当前比赛结束后可用。 

### 为什么它有效

 处理任何前缀后`s`,`j`是从开头开始的最大连续字符数`t`处理后的前缀可以使用贪婪选择进行匹配。 更具体地说，每个匹配的字符`t`被分配到越来越重要的位置`s`，所以每当`j`达到`len(t)`，我们已经显式构造了一个有效的子序列。 

相反，每当算法跳过一个字符`s`，该字符要么与下一个所需字符不同，要么没有剩余要求。 如果它匹配下一个所需的字符，则消耗最早出现的此类字符不会导致以后的匹配变得不可能，因为在它之后可以使用的每个位置仍然可用。 因此，如果贪婪扫描在匹配所有之前完成`t`，早期匹配的任何替代选择都无法产生有效的子序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    j = 0

    for c in s:
        if j < len(t) and c == t[j]:
            j += 1
            if j == len(t):
                print("YES")
                return

    print("NO")

if __name__ == "__main__":
    solve()
```输入被读取`readline`，适用于长度达一百万的字符串。 这`.strip()`call 删除换行符，而不更改实际字符串中的任何小写英文字母。 

变量`j`是唯一需要的状态。 它始终指向所需的下一个字符`t`。 什么时候`s`包含该字符，我们前进`j`; 否则，当前字符`s`可以安全地被忽略。 

条件`j < len(t)`阻止访问`t[j]`在整个猜测已经匹配之后。 即时的`YES`return 也避免了扫描剩余部分`s`，尽管即使没有这种优化，算法仍将保持线性。 

不存在整数溢出问题，因为Python整数是任意精度的，并且该算法仅维护一个由长度限制的指针`t`。 更重要的是，没有二维表，因此与 256 MB 的限制相比，内存使用量仍然很小。

 ## 边缘情况

 当字符串长度为 1 时，算法仅执行一次比较。 用于输入```
a
a
```

`j`从零开始，唯一匹配的字符`t[0]`， 和`j`变成一，等于`len(t)`。 结果是`YES`。 为了```
a
b
```比较失败，`j`保持为零，扫描结束，给出`NO`。 

要求每个字符的长度相等`s`被使用。 为了```
abc
acb
```算法匹配`a`，然后匹配`c`，之后需要`b`。 其余部分`s`只是`c`，无法提供`b`，所以结果是`NO`。 该算法从不假设相等的长度意味着相等。 

重复的字符需要有足够多的不同出现次数。 为了```
aaaa
aaaaa
```对于四个字符中的每一个，指针前进一次`s`，达到`j = 4`。 目标的长度为 5，因此扫描以 1 不匹配的结果结束`a`并返回`NO`。 为了```
aaaaa
aaa
```第三个`a`进步`j`三、立即完成目标并生产`YES`。 

目标可以精确地完成源的最后一个字符。 为了```
abcx
abc
```指针从`0`到`1`， 然后`2`， 然后`3`阅读时`a`,`b`， 和`c`。 自从`j == len(t)`处理后立即`c`，算法返回`YES`不需要另一个源字符。 这个边界条件就是为什么完成检查必须在指针前进后立即发生。 

最大尺寸的情况与小情况的行为相同。 拥有一百万`a`两个字符串中的字符，每个源字符都与当前目标字符匹配，最终比较后目标指针达到一百万。 该算法执行线性工作，而不是尝试将每个源位置与每个目标位置进行比较，这使得解决方案在规定的限制下可行。
