 ## 解决方案
 ## 问题理解

 我们得到一个数组和一个衡量其“变化程度”的具体度量：连续元素之间的绝对差之和。 该值捕获当我们从左到右遍历数组时数组振荡的程度。 

任务不是修改值，而是选择一个保留与原始数组完全相同的总振荡的子序列。 同时，我们希望这个子序列尽可能短。 

因此，核心问题是结构性的：哪些元素对于保持全部运动量实际上是必要的，哪些元素是多余的，因为它们位于单调运动的直线段上？ 

约束足够大，以至于每个测试用例的任何解决方案都必须是线性的或接近线性的。 所有测试的总长度都是有限的，因此需要单遍或基于排序的方法。 任何二次子序列 DP 或强力移除策略都会立即失败。 

一个常见的失败案例是移除过于激进。 例如，在像这样的数组中$[1, 2, 3, 2, 1]$，去除中间的峰值或谷值会改变总对比度。 仅保留局部极值而不仔细检查过渡的简单方法可能会错误地折叠片段并降低对比度。 

另一个微妙的问题是持续运行。 在类似的事情中$[5, 5, 5, 5]$，正确答案是$1$，但是任何盲目保留每个单调线段端点的方法都会错误地输出$2$或更多。 

## 方法

 蛮力的想法是尝试所有子序列，计算它们的对比度，并检查哪些子序列与原始数组的对比度匹配。 这在概念上是有效的，因为它直接强制执行条件，但子序列的数量大致呈指数增长$2^n$，即使对于$n = 30$。 

关键的洞察力是了解真正有助于对比度的因素。 表达式$|a_i - a_{i+1}|$仅当方向发生变化或值发生变化且未与平坦线段对齐时才会增加。 如果我们看一下单调递增的运行，每个中间点都不会添加任何新的“方向信息”，它只会将单个斜率分成更小的相同贡献。 

这表明单调段中的大多数元素都是冗余的。 只有方向改变或平等打破平台的转变才是必要的。 事实上，保留对比度的最小子序列正是压缩相等邻居然后仅保留斜率改变符号或值移动方向改变的点之后的“转折点”序列。 

因此，问题简化为将数组压缩为严格增加和减少的交替段，并计算这些段的数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(2^n \cdot n)$|$O(n)$| 太慢了 |
 | 最佳 |$O(n)$|$O(1)$额外 | 已接受 |

 ## 算法演练

 我们处理数组的同时跟踪运动方向如何变化。 

1.首先压缩连续的相等值。 它们不会对对比度产生影响，因为它们的差异为零，并且不会影响方向。 
2.如果压缩后数组有大小$1$，答案是$1$因为没有对比可以保留。 
3. 然后，我们计算连续元素之间的差异符号，将每个相邻元素对视为递增或递减。 
4. 我们计算该符号沿数组变化的次数。 每个符号变化对应于任何保留完整对比度的子序列中的必要断点。 
5.最小子序列大小比符号变化的数量大1，因为每个段贡献至少一个代表元素。 

这样做的原因是，严格单调段中的任何中间元素都可以在不改变绝对差之和的情况下被删除，因为伸缩保留了总变化。 

## 为什么它有效

 阵列的对比度沿着最大单调段分解。 在严格递增或递减的段内，除了端点已定义的内容之外，每个内部点都不会产生额外的变化。 

任何保留对比度的子序列都必须保留变化方向切换的所有点，因为删除这样的点会将两个相反的斜率合并为单个直接跳跃，这会严格减少或改变总变化。 

因此，最小子序列恰好对应于数组的分段单调分解中的极值点序列。 这些极值点的数量正好是去除重复后斜率符号变化的数量加一。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # remove consecutive duplicates
        b = []
        for x in a:
            if not b or b[-1] != x:
                b.append(x)

        if len(b) == 1:
            print(1)
            continue

        # compute sign changes
        changes = 0
        prev = 0

        for i in range(1, len(b)):
            if b[i] > b[i - 1]:
                cur = 1
            else:
                cur = -1

            if cur != prev and prev != 0:
                changes += 1

            prev = cur

        print(changes + 1)

if __name__ == "__main__":
    solve()
```该解决方案首先压缩重复项，因为相等的连续值不会影响对比度。 然后，它扫描简化后的数组，同时跟踪每个步骤是增加还是减少。 每次这个方向翻转时，我们都需要在子序列中添加一个新的基本元素。 

主要的微妙之处是正确初始化先前的方向。 我们从中立状态开始，只有在确定方向后才开始计算变化。 另一个微妙之处是相等性已被删除，因此每个相邻对都有严格的比较，避免未定义方向的情况。

 ## 边缘情况

 一个完全恒定的数组，例如$[7, 7, 7, 7]$压缩为单个值。 算法立即返回$1$，反映不存在过渡，也不需要保留对比结构。 

严格单调数组，例如$[1, 2, 3, 4, 5]$方向只有一个，没有变化。 答案就变成了$2$，因为每个方向段有一个端点就足够了。 

像这样的交替数组$[1, 3, 1, 3, 1]$压缩后产生多个符号翻转，并且每个翻转都被捕获为必要的断点，确保子序列保留每次上升和下降，而不会破坏对比结构。
