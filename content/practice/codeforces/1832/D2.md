 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，最初为红色。 在每个操作中，您选择一个元素。 如果它是红色的，则将其增加操作数并将其切换为蓝色。 如果它是蓝色的，则将其减少操作数并将其切换回红色。 每个操作都有一个从 1 开始的顺序索引。对于查询`k`，我们需要最小元素的最大可能值`k`运营。 每个查询都是独立的； 数组在每次查询之前都会重置。 

挑战来自两个主要限制。 数组最多可以有20万个元素，操作次数最多可以达到10亿次。 跟踪颜色并逐个元素更新数组的简单模拟是立即不可行的，因为迭代十亿次操作远远超出了时间限制。 

非明显的边缘情况包括最小元素位于开头或结尾的数组、元素全部相等的数组以及其中的查询`k`小于`n`或非常大。 例如，如果`a = [5,5]`和`k = 1`，最佳移动是将较小的元素（任一元素）加 1。 假设操作必须均匀分布的粗心方法可能会错误地减少可实现的最大最小值。 另一个微妙的情况是当`k`超过元素数量； 我们必须考虑在多个元素之间优化分配操作，以最大化最小值。 

## 方法

 暴力方法将按顺序模拟每个操作，跟踪每个元素的颜色和值。 对于每个查询`k`，我们将从操作 1 迭代到`k`，在每一步中选择能够最小化降低最终最小值的风险的元素。 虽然原则上是正确的，但这种方法执行`O(k)`每个查询更新，这在以下情况下是禁止的`k`可以是 10^9。 

关键的见解是每个元素可以多次作用，并且增量的总和是可预测的。 如果我们想象`x`操作分布到单个元素，最终效果是算术序列的加法和减法的组合。 最大化最小值的最佳策略是首先在最小元素之间分配操作，因为增加最小元素会提高全局最小值。 这将问题简化为二分搜索：寻找候选最小值`m`，我们能否分布操作，使得每个元素至少达到`m`？ 如果是，我们可以尝试更高的最小值； 如果不是，我们就降低目标。 计算每个候选最小值所需的操作为`O(n)`，因此对潜在最小值的二分搜索给出`O(n log(max_a + k))`，这在约束条件下是可行的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(q * k) | O(n) | 太慢了 |
 | 最佳 | O(q * n * log(max_a + k)) | O(q * n * log(max_a + k)) | O(n) | 已接受 |

 ## 算法演练

 1. **对数组进行排序**。 这使我们能够快速识别最小的元素，并推理如何有效地提高最小值。 
2. **定义可行性检查**。 对于最低目标`m`，计算每个元素需要多少次操作`a[i]`至少达到`m`。 对于每个元素，如果它小于`m`，我们计算将其增加到过去所需的最小操作数`m`，使用连续操作增量之和的公式。 这来自解决`sum_{j=1}^{x} j >= m - a[i]`，这减少到寻找最小的`x`这样`x*(x+1)/2 >= m - a[i]`。 这是因为对元素应用操作会交替颜色，但会增加操作索引步骤的净效果。 
3. **对所有元素所需的操作进行求和**。 如果总数小于或等于`k`，目标最小值`m`是可以实现的。 
4. **二分查找答案**。 初始化`lo`作为数组的当前最小值并且`hi`作为`max(a) + k`。 尽管`lo < hi`，检查中点。 如果可行就搬`lo`向上; 否则，移动`hi`向下。 在最后，`lo`是可达到的最大最小值。 
5. **使用相同的程序独立回答每个查询**。 

为什么有效：将操作贪婪地分配给最小的元素可以保证不会人为地留下任何元素。 二分查找之所以有效是因为如果最小`m`是可以实现的，所有较小的值都是可以轻松实现的。 整数和公式确保我们正确计算每个元素的最少操作，即使对于大型`k`。 

## Python 解决方案```python
import sys, math
input = sys.stdin.readline

def min_ops_needed(a, target):
    ops = 0
    for val in a:
        if val >= target:
            continue
        diff = target - val
        # solve x*(x+1)/2 >= diff for x
        x = math.ceil((-1 + math.sqrt(1 + 8*diff)) / 2)
        ops += x
    return ops

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    queries = list(map(int, input().split()))
    a.sort()
    
    for k in queries:
        lo = min(a)
        hi = max(a) + k + 1
        while lo < hi:
            mid = (lo + hi) // 2
            if min_ops_needed(a, mid) <= k:
                lo = mid + 1
            else:
                hi = mid
        print(lo - 1, end=' ')
    print()

if __name__ == "__main__":
    solve()
```这`min_ops_needed`函数使用二次公式来计算每个元素达到候选最小值所需的操作数。 排序`a`确保我们首先有效地推理最小的元素。 二分搜索缩小了可行的最小值，而无需迭代所有可能的值`10^9 + 10^9`。
