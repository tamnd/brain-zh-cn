 ## 解决方案
 ## 问题理解

 我们给出了许多独立的整数范围。 对于每个范围$[l, r]$，我们需要选择两个不同的整数$x$和$y$在此区间内，使得它们的最小公倍数也在同一区间内。 

因此，任务不是优化和或差之类的东西，而是找到在 LCM 操作下“保持稳定”的对：两个输入都在范围内，并且它们的 LCM 不会逃脱它。 

输出要么是这样的一个对，要么是一个不存在有效对的声明。 如果存在多个有效的解决方案，我们可以自由打印任何有效的解决方案。 

约束在这里极其重要。 我们最多可能有$10^4$测试用例，每个范围端点可以大到$10^9$。 这排除了尝试所有对甚至范围内所有候选的任何解决方案。 当最坏情况范围跨越整个测试用例时，即使迭代每个测试用例的单个大间隔也是不可能的$10^9$规模。 

一个简单的配对检查会检查所有$(x, y)$在$[l, r]$，每次计算LCM。 这是间隔大小的二次方，这是立即不可行的。 

当间隔太紧时，会出现微妙的边缘情况。 例如，如果$r = l + 1$，我们只有一对可能的$(l, l+1)$。 有时这有效，有时失败。 例如，在$[88, 89]$，唯一的一对是 88 和 89，并且由于它们是互质的，所以它们的 LCM 是$88 \cdot 89$，它远远超出了范围，所以答案一定是$-1, -1$。 

另一种边缘情况是当间隔很小但包含具有除数关系的数字时，例如$[2, 4]$。 这里选择$x=2, y=4$有效是因为$\mathrm{LCM}(2,4)=4$，它保持在区间内。 

核心困难是在不枚举候选者的情况下决定何时存在这样的“在 LCM 下封闭”对。 

## 方法

 暴力方法尝试每一对$(x, y)$在范围内$[l, r]$并检查是否$\mathrm{LCM}(x, y)$位于同一范围内。 这是正确的，因为它直接遵循问题中的条件。 但是，如果间隔有大小$k$，这需要$O(k^2)$检查，每次检查都涉及计算 LCM。 在最坏的情况下$k$可能很大，使得这种方法不可能实现。 

关键的观察是我们实际上不需要在区间内搜索。 问题的结构强烈表明唯一有用的候选对是非常简单的东西。 如果我们看看像这样的成功例子$(2,4)$或者$(6,7)$，我们注意到一种模式：要么数字是连续的，要么一个是另一个的倍数。 

如果我们尝试这对$(l, 2l)$，就变得有趣了。 的LCM$l$和$2l$总是$2l$， 自从$2l$已经是的倍数$l$。 这立即保证了 LCM 等于较大的元素。 所以条件简化为检查是否$2l \le r$。 

这将整个问题分解为每个测试用例的一次构造尝试。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O((r-l)^2)$|$O(1)$| 太慢了 |
 | 最佳 |$O(1)$每个测试用例|$O(1)$| 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 读取数值$l$和$r$。 这些定义了数字和 LCM 的允许范围。 
2. 尝试使用范围内的最小数字构建候选对。 我们设定$x = l$因为任何有效的解决方案都可以在可能的情况下向下移动而不失去可行性，并且从最小值开始给出了将 LCM 保持在区间内的最佳机会。 
3. 设置$y = 2l$。 这一选择确保了干净的 LCM 结构，因为一个数字可以除另一个数字。 我们避免显式计算 gcd 或 LCM。 
4. 检查是否$y \le r$。 如果这个成立，那么两个数字都在范围内，并且它们的 LCM 恰好是$y$，也在范围之内。 
5. 如果条件不成立，则输出$-1, -1$，因为这种类型的结构无法容纳在该区间内。 

### 为什么它有效

 正确性依赖于这样一个事实：任何有效的对必须要么有一个数字除另一个数字，要么产生一个增长超出间隔大小的 LCM。 施工$(l, 2l)$是最小可能的非平凡多重关系。 如果即使是这个最小的倍数也超过$r$，然后任何其他涉及$l$或更大的值只会产生更大的 LCM。 因此，不存在有效的对。 相反，当$2l \le r$，这对$(l, 2l)$始终有效，因为可分性保证$\mathrm{LCM}(l, 2l)=2l$，其保持在界限内。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
out = []

for _ in range(t):
    l, r = map(int, input().split())
    
    if 2 * l <= r:
        out.append(f"{l} {2*l}")
    else:
        out.append("-1 -1")

print("\n".join(out))
```该解决方案完全是由观察驱动的，即唯一有意义的候选者是$(l, 2l)$。 该代码避免了 gcd 或 LCM 的任何计算，因为可分结构通过构造是显式的。 

唯一微妙的一点是确保整数乘法不会溢出典型边界，但 Python 可以安全地处理大整数。 支票$2*l \le r$是完整的决策逻辑。 

## 工作示例

 ### 示例 1

 输入：```
l = 1, r = 1337
```我们测试施工$x = 1$,$y = 2$。 

| 步骤| x| y | 状况 |
 | ---| ---| ---| ---|
 | 建设| 1 | 2 | - |
 | 检查 | 1 | 2 | 2 ≤ 1337 |

 由于条件成立，我们输出$1, 2$。 LCM 为 2，位于范围内。 

这显示了间隔足够大，最小元素加倍仍然有效的情况。 

### 示例 2

 输入：```
l = 88, r = 89
```我们构建$x = 88$,$y = 176$。 

| 步骤| x| y | 状况 |
 | ---| ---| ---| ---|
 | 建设| 88 | 88 176 | 176 - |
 | 检查 | 88 | 88 176 | 176 176 ≤ 89 失败 |

 由于条件不成立，我们输出$-1, -1$。 任何其他对都是不可能的，因为唯一可用的对要么不存在，要么产生远远超出范围的 LCM。 

这演示了紧间隔故障情况。

 ## 边缘情况

 当区间仅包含两个连续数字时，例如$[88, 89]$, 施工产生$y = 2l = 176$，立即超出范围。 该算法正确地拒绝了这种情况，因为条件$2l \le r$失败，所以输出$-1, -1$。 任何替代对都是不可能的，因为在可以与 88 形成有界 LCM 的范围内不存在第二个整数。 

当间隔正好是$[l, l+1]$，唯一可能的对被强制，并且算法通过加倍规则隐式测试该对。 自从$2l > l+1$为所有人$l \ge 1$，每个这样的区间都会被正确拒绝，除非它退化为特殊的可分结构，例如$[2,4]$， 在哪里$2l = 4 \le r$，产生有效的解决方案。
