 ## 解决方案
 ## 问题理解

 我们得到一个无向连通图，其中每条边都可以变成我们选择的单向边或保留为双向边。 保持双向是昂贵的，因为每个这样的边缘都会对成本产生影响。 有向边是自由的，但只能在选定的方向上使用，而无向边可以在两个方向上遍历。 

有一个顶点子集称为特殊顶点。 选择方向后，如果每个特殊顶点都可以使用生成的混合图中允许的移动到达该顶点，则该顶点被称为良好顶点。 我们从每个好的顶点获得利润，等于分配给该顶点的给定值。 总分是所有好顶点的利润减去无向边的总成本。 

任务是为每个被视为所需的好顶点的顶点计算最大可能得分。 

关键的困难在于，可达性的结构在全局上取决于边的方向，并且改变一条边可以同时影响多对顶点之间的可达性。 这立即排除了任何独立处理顶点的方法。 

约束条件很大，有多达三十万个顶点和边。 任何以幼稚的方式重新计算可达性或单独优化每个根的方向的解决方案都将无法扩展。 即使对每个顶点重复进行线性或近线性图遍历也会太慢。 

当图表包含来自图表不同部分的方向要求相互冲突的循环时，就会出现微妙的边缘情况。 如果我们贪婪地在本地定位边缘，我们很容易造成某些特殊顶点无法到达所选根的情况，即使不同的全局方向允许它。 例如，在特殊顶点位于不同角的三角形中，如果我们忽略路径如何交互，局部一致的方向可能仍然会破坏全局可达性。 

## 方法

 蛮力的观点是尝试所有可能的边缘方向。 对于每个方向，我们将计算从所有特殊顶点可以到达哪些顶点，然后将它们的值相加，减去无向边的成本。 即使忽略方向的指数数量，仅可达性计算在图大小上也是线性的，因此这是完全不可行的。 

更结构化的蛮力是固定一个根顶点 i，并在所有特殊顶点都能到达 i 的约束下尝试构造一个使分数最大化的最佳方向。 即使如此，人们可能会尝试贪婪地决定边缘方向或重复重新计算连接，导致每个根至少需要 O(m) 工作，这对于 n 高达 3⋅10^5 来说太慢了。 

关键的观察结果是，所有特殊顶点的可达性对高度连接区域内的各个边缘方向不敏感。 方向选择唯一重要的地方是桥梁，因为在 2 边连接的组件内，我们始终可以重新路由路径。 这建议将图压缩到桥树中，其中每个节点都是双连接组件，每条边都是桥。 

在这棵树上，每个桥的行为就像一个二元决策点。 如果我们将其定向到一个方向，则跨越它的可达性就变成单向的。 如果我们支付它的成本，我们就可以双向穿越它。 整个问题归结为，对于每个桥，我们是否需要根据特殊顶点的分布方式来决定是否需要双向遍历。

从这个角度来看，固定一个根i就变得有意义了：所有特殊顶点必须能够到达桥树中包含i的组件。 我们总是可以将每个桥定向到 i，这已经允许每个顶点到达 i 而无需支付成本。 然而，这忽略了隐藏在目标中的第二个约束：我们不仅确保可达性，而且还最大化在单一一致方向选择下从所有特殊点同时可达的顶点集。 不同可达性要求之间的权衡迫使某些网桥在最佳配置中变成双向，这就是成本出现的地方。 

将图简化为其桥树后，问题就变成了根选择上的树 DP，其中每个桥根据是否必须支持由特殊顶点引起的冲突流来贡献成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力定向 + 每个案例的 BFS | 指数 / O(nm) | O(n + m) | 太慢了 |
 | 桥树+树结构上的DP | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 将图分解为其双连通分量并构建桥树。 每个节点代表一个 2 边连接的组件，每条边对应于具有给定成本的桥。 

此步骤删除了所有不相关的内部结构，因为在组件内可以不受限制地实现任何所需的连接。 
2. 将每个原始顶点映射到桥树中其组件，并识别哪些组件包含特殊顶点。 

在此转换之后，所有约束仅取决于特殊组件在树中的分布方式。 
3. 任意求桥树的根，并计算子树信息，具体是每个节点的每个子树中有多少个特殊顶点。 

这使我们能够确定对于任何桥，该桥的两侧是否存在特殊顶点。 
4. 对于每个网桥，确定在给定的根选择下它是否是“强制”的。 当特殊顶点出现在桥梁的两侧时，桥梁就会被强制，因为信息或可达性要求必须在结构的不同部分在两个方向上通过它，而单个定向无法满足这一要求。 

当桥梁被迫建造时，我们需要支付其成本，因为它必须在两个方向上都可用。 
5. 对于每个可能的根组件，计算所有强制桥所贡献的总成本。 这可以使用桥树上的重新根 DP 在 O(n) 内完成，其中跨边缘移动根会更新被视为强制的桥集。 
6. 根的利润是组件中所有顶点的值之和，这些组件在所选方向下从所有特殊顶点仍然可同时到达，减去计算的强制桥成本。 

由于组件内部的可达性始终是可以实现的，因此该决策完全简化为桥接约束。 
7. 通过将组件答案映射回原始顶点，输出每个顶点的计算值。 

### 为什么它有效

 关键的不变量是，在任何双连通组件内，无论边方向如何，顶点之间的可达性始终可以保留，因此所有全局约束都会崩溃到桥树。 在这棵树上，当且仅当每个特殊组件都可以到达该顶点时，该顶点才是有效的饱和根，并且对该条件的任何阻碍仅来自于其移除将特殊顶点分隔到不同侧面的桥。 当选择根时，此类桥会产生不可避免的双向要求，而这些要求完全决定了成本。 由于每个配置都对应于网桥树上的某些方向分配，并且每个有效分配都可以通过选择哪些网桥为双向性付费来表示，因此基于重新根的 DP 可以毫无遗漏地捕获所有最佳配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m, k = map(int, input().split())
    special = set(map(int, input().split()))
    c = list(map(int, input().split()))
    w = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    edges = []

    for i in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, i))
        g[v].append((u, i))
        edges.append((u, v))

    tin = [-1] * n
    low = [-1] * n
    timer = 0
    is_bridge = [False] * m

    def dfs(v, pe):
        nonlocal timer
        timer += 1
        tin[v] = low[v] = timer
        for to, ei in g[v]:
            if ei == pe:
                continue
            if tin[to] != -1:
                low[v] = min(low[v], tin[to])
            else:
                dfs(to, ei)
                low[v] = min(low[v], low[to])
                if low[to] > tin[v]:
                    is_bridge[ei] = True

    dfs(0, -1)

    comp = [-1] * n
    cid = 0

    stack = []

    comp_g = []

    def dfs_comp(v, cid):
        stack = [v]
        comp[v] = cid
        has_special = special.__contains__(v + 1)
        while stack:
            x = stack.pop()
            for to, ei in g[x]:
                if comp[to] == -1 and not is_bridge[ei]:
                    comp[to] = cid
                    stack.append(to)

    for i in range(n):
        if comp[i] == -1:
            dfs_comp(i, cid)
            cid += 1

    comp_special = [0] * cid
    comp_weight = [0] * cid

    for v in range(n):
        if (v + 1) in special:
            comp_special[comp[v]] = 1
        comp_weight[comp[v]] += c[v]

    tree = [[] for _ in range(cid)]

    for i, (u, v) in enumerate(edges):
        cu, cv = comp[u], comp[v]
        if cu != cv:
            tree[cu].append((cv, w[i]))
            tree[cv].append((cu, w[i]))

    sz = [0] * cid
    dp = [0] * cid

    total_special = sum(comp_special)

    def dfs1(v, p):
        sz[v] = comp_special[v]
        for to, wt in tree[v]:
            if to == p:
                continue
            dfs1(to, v)
            sz[v] += sz[to]

    dfs1(0, -1)

    def dfs2(v, p):
        for to, wt in tree[v]:
            if to == p:
                continue
            dp[to] = dp[v]
            if sz[to] > 0 and total_special - sz[to] > 0:
                dp[to] += wt
            dfs2(to, v)

    dfs2(0, -1)

    ans_comp = [comp_weight[i] - dp[i] for i in range(cid)]

    for v in range(n):
        print(ans_comp[comp[v]], end=" ")

if __name__ == "__main__":
    solve()
```实现首先使用标准 DFS 低链路过程查找所有网桥。 任何删除会增加连接组件数量的边都被标记为桥。 

接下来，通过遍历所有非桥边将顶点压缩为 2 边连接的组件。 每个组件都会累积其顶点的总值以及一个指示其是否包含至少一个特殊顶点的标志。 

压缩后，构建一棵树，其中边与原始图的桥完全对应，并且每条边保留其原始权重。 

第一个 DFS 为每个组件计算其子树中有多少个特殊顶点。 这是至关重要的，因为只有当桥的每一侧至少分隔一个特殊顶点时，它才是相关的。 

第二个 DFS 重新确定树的根，并累积相对于当前根位置“切割”的桥所贡献的成本。 当将根移动到一条边上时，我们会更新该边是否将特殊顶点分为两侧，如果是，我们会添加其成本。 

最后，每个组件的答案是其总顶点值减去累积成本，并且为该组件中的所有顶点打印该值。

 ## 边缘情况

 没有桥的图是最干净的情况。 每个顶点都属于单个组件，因此 DP 永远不会累积任何桥梁成本。 该算法将整个图压缩为一个节点，每个顶点接收相同的总值，这与无需支付任何边成本即可保留所有顶点之间的可达性这一事实相匹配。 

树是相反的极端，每条边都是一座桥。 在这种情况下，每条边都可能会产生成本，具体取决于特殊顶点在其上的分割方式。 当 DFS 累积将特殊顶点分成树的不同部分时，它会正确地对每个桥进行一次计数，从而匹配问题的最坏情况敏感性。 

所有特殊顶点都位于单个组件中的配置表明，没有桥被强制。 特殊顶点的子树计数确保每个桥的贡献为零，因为没有边分隔特殊节点，因此答案纯粹简化为顶点值。
