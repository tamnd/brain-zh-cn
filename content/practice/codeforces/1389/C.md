 **已验证：** 否

 ## 解决方案
 ## 问题理解

 我们得到一串数字，并允许在任何我们喜欢的地方删除字符，保留剩余字符的顺序。 目标是将字符串转换为一种称为“good”的特殊形式。 

当应用左循环移位产生与应用右循环移位相同的字符串时，该字符串被认为是好的。 循环移位将第一个字符移动到末尾（左移）或将最后一个字符移动到前面（右移），并且在良好的字符串中，这两种操作都会产生相同的结果。 

关键问题不是直接构造一个好的字符串，而是删除尽可能少的字符，使剩下的子序列变得好。 

因此，输出是所需的最小删除次数，这相当于最大化良好子序列的长度。 

测试用例总长度的限制最多为 2 · 10^5。 这立即排除了每个测试用例的任何二次方，并将我们推向每个测试的线性或近线性解决方案或在较小的固定状态空间上迭代的解决方案。 

一种简单的方法会尝试所有子序列或所有删除，但即使检查单个子序列的有效性也需要线性时间。 对于指数级多的子序列，这是不可能的。 

当字符串看起来已经高度规则但不完全交替时，就会出现微妙的边缘情况。 例如，在`100120013`，删除哪些字符才能达到最佳结构并不明显。 在不了解全局模式的情况下贪婪地删除“难看”的字符很容易错过最佳子序列。 

另一种失败模式是假设生成的好字符串必须具有所有相同的字符。 对于最佳答案有时确实如此，但在中间推理中并不总是必需的。 

## 方法

 首先要了解“好”在结构上实际执行的是什么。 我们不是直接模拟循环移位，而是逐位置比较两个移位版本。 

设字符串为`t1 t2 ... tn`。 

左移给出`t2 t3 ... tn t1`。 

右移给出`tn t1 t2 ... t_{n-1}`。 

为了使它们相同，相应的位置必须匹配。 这就创建了一个平等的制度：`t2 = tn`,`t3 = t1`,`t4 = t2`， 等等。 

遵循这些约束揭示了周期为 2 的重复模式。每隔一个字符都必须匹配，这意味着所有奇数位置彼此相同，所有偶数位置彼此相同。 

因此，任何好的字符串都必须在两个固定数字之间交替，例如`a b a b a b ...`或者`b a b a b a ...`，包括退化的情况`a = b`，它产生一个常量字符串。 

因此，问题变成：从原始字符串中，根据需要删除尽可能少的字符，以便剩余的子序列在两个选定的数字之间交替。 

暴力方法会尝试每个子序列，或者更合理的是，尝试删除每个字符子集并检查其余部分是否良好。 这会导致字符串长度呈指数行为，并且在小输入之外变得不可行。 

关键的观察是有效字符串的结构仅取决于选择一对有序的数字`(a, b)`。 一旦这个对被固定，就可以贪婪地构造最好的可能子序列：从左到右扫描并仅当字符与预期的交替模式匹配时才保留字符。 我们可以有效地评估所有 100 个可能的数字对。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对子序列的暴力破解 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 尝试使用贪婪构造的所有数字对 | O(100·n) | O(100·n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将任务转换为寻找在两个固定数字之间交替的最长子序列。 

1.修复一对有序数字`(a, b)`。 

这对代表最终字符串的预期交替模式。 我们将尝试所有 100 种可能性。 
2. 计算从期望开始的最长子序列`a`。 

我们从左到右扫描字符串。 每当我们看到预期的字符时，我们都会将其转换为另一个数字。 

这是有效的，因为采取较早的有效匹配总是为未来的匹配留下更多的灵活性。 
3. 计算从期望开始的最长子序列`b`。 

这捕获了交替奇偶校验开始，因为最佳交替子序列可能以任一数字开始。 
4. 取该对的两个起始选择的最大结果`(a, b)`。 
5. 对所有数字对重复并跟踪全局最大子序列长度。 
6.答案是`n - best_subsequence_length`。 

为什么这就足够了：每个有效的好字符串必须在两个数字之间交替，并且每个交替子序列完全对应于某些选择`(a, b)`加上起始位置。 贪婪扫描为每个固定配置生成最佳子序列，因为任何跳过的有效匹配只会延迟或阻止未来所需的匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def best_for_pair(s, a, b):
    # try starting with a
    need = a
    cnt1 = 0
    for ch in s:
        if ch == need:
            cnt1 += 1
            need = b if need == a else a

    # try starting with b
    need = b
    cnt2 = 0
    for ch in s:
        if ch == need:
            cnt2 += 1
            need = a if need == b else b

    return max(cnt1, cnt2)

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)

        best = 1
        for i in range(10):
            for j in range(10):
                best = max(best, best_for_pair(s, str(i), str(j)))

        print(n - best)

if __name__ == "__main__":
    solve()
```实现的核心思想是将交替子序列检查隔离到固定数字对上的辅助函数中。 数字上的双循环大小恒定，因此复杂性与字符串长度保持线性关系。 

一个微妙的实现细节是处理案例`a == b`。 在这种情况下，交替过程退化为选择所有出现的单个数字，并且相同的贪婪逻辑仍然可以正确工作，因为期望永远不会改变。 

## 工作示例

 ### 示例 1：`95831`我们尝试成对，但重点是`(5,1)`因为它产生了强交替子序列。 

| 步骤| 人物 | 预计| 拿？ | 序列长度|
 | ---| ---| ---| ---| ---|
 | 1 | 9 | 5 | 没有 | 0 |

 | 3 | 8 | 1 | 没有 | 1 |

 | 5 | 1 | 1 | 是 → 预计 5 | 2 |

 所有对的最佳子序列长度是 2，所以答案是`5 - 2 = 3`。 

这表明最佳结构与原始字符串中的邻接无关，而是与选择一致的交替模式有关。

 ## 边缘情况

 常见的边缘情况是所有字符都相同，例如`777777`。 该算法评估对`(7,7)`并正确地将整个字符串计数为有效的交替子序列，因为不需要切换。 

另一种情况是当最佳模式使用原始字符串中相距较远的两个不同数字时，例如`95831`。 贪婪扫描仍然可以找到正确的子序列，因为它不依赖于邻接性，只依赖于顺序保存。 

另一种情况是交替以频率较低的数字开始。 例如，在`100120013`，最佳子序列可能以字符串中稍后出现的数字开始。 该算法通过显式尝试每个数字对的两种起始状态来处理此问题，确保不会遗漏任何配置。
