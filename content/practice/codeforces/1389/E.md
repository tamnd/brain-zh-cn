 ## 解决方案
 ## 问题理解

 我们有一个虚构的日历系统，其中时间分为三层。 一年有`m`月，每个月恰好包含`d`天，每周重复一次`w`天。 一年的第一天从工作日索引 1 开始，所有后面的工作日都以周期循环`w`。 

该系统中的每一天都可以通过两种不同的方式进行标识：通过其在一个月内的位置以及通过其全球工作日标签。 由于月份是统一的，因此对于工作日计算唯一重要的是一年中的线性日索引。 

任务是考虑所有不同月份对`(x, y)`和`x < y`，并检查它们之间的对称条件。 对于要计数的一对，“y 月的 x 天”的工作日必须与“x 月的 y 天”的工作日匹配。 我们必须计算有多少这样的对满足这种对称性。 

尽管该声明是用日历术语表述的，但一切都简化为一维时间轴上的算术：每天都有一个全局索引，工作日仅取决于该索引模`w`。 

约束条件非常大，每个`m`,`d`， 和`w`最多`10^9`直至`1000`测试用例。 任何直接检查月份对的方法，这将是二次的`m`，是不可能的。 甚至线性依赖`m`在最坏的情况下，每个测试用例太大。 

天真的尝试会尝试检查每一对`(x, y)`并使用模运算计算工作日差异。 这导致`O(m^2)`每个测试的操作数，当`m`很大。 

一个更微妙的失败案例来自于尝试逐月模拟工作日。 尽管每个月的轮班很简单，但累积的偏移量`m`几个月，然后检查所有对仍然会导致二次工作或在约束下破坏的大量预计算。 

## 方法

 核心困难在于“y 月的 x 天”和“x 月的 x 天”都依赖于相同的线性日历，因此我们正在比较由相同算术级数构建但在交换索引处评估的两个表达式。 

让我们分配每个月`i`当年的起始偏移量。 由于每个月都有`d`天，月初`i`是`(i-1) * d`。 因此，全球日指数`k`一个月内`i`是：`A(i, k) = (i-1) * d + k`这一天的工作日是`A(i, k) mod w`。 

成对的条件`(x, y)`变成：`A(y, x) ≡ A(x, y) (mod w)`两边展开：`(y-1)d + x ≡ (x-1)d + y (mod w)`重新排列：`(y-x)d + x - y ≡ 0 (mod w)`因素：`(y-x)(d - 1) ≡ 0 (mod w)`现在结构变得清晰了：条件仅取决于差异`t = y - x`，而不是绝对位置。 每个有效对仅由月份之间的差距决定。 

所以对于每一个`t > 0`，我们需要计算有多少对`(x, x+t)`存在，即`m - t`，并检查是否：`t * (d - 1) ≡ 0 (mod w)`因此，问题归结为计算有效差异`t`根据它们生成的对数量进行加权。 

蛮力会迭代所有`t`从`1`到`m-1`并检查已经存在的条件`O(m)`每个测试用例仍然太大`m`是`10^9`。 

关键的见解是将所有`t`满足模整除条件。 我们需要：`w | t * (d - 1)`让`g = gcd(w, d - 1)`。 那么条件就简化为：`(w / g) | t`如此有效`t`正好是`k = w / gcd(w, d - 1)`。 

现在问题变成了纯粹的算术：计算所有的倍数`k`最多`m-1`，并且对于每个这样的`t`， 添加`m - t`。 

这将整个计算减少为对多个数的算术级数求和`k`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解对 | O(m^2) | O(1) | O(1) | 太慢了 |
 | 迭代差异 | O(米) | O(1) | O(1) | 太慢了 |
 | 基于 GCD 的算术计数 | 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们现在将算术归约转化为直接计算。 

1. 计算`a = d - 1`。 这是派生同余中出现的转变。 如果`a = 0`，工作日条件显着简化，因为所有逐月偏移量都在表达式内消失。 
2. 计算`g = gcd(w, a)`。 这提取了周长和月班次之间的共同整除结构。 
3. 定义`k = w // g`。 这是最小步长，使得每个有效差异`t`必须是的倍数`k`。 
4. 如果`k > m - 1`，不存在有效差异。 返回`0`。 这是因为最小的有效`t`已经超出了可能的月份差距范围。 
5. 否则，考虑所有倍数`t = k, 2k, 3k, ... ≤ m-1`。 令最大的倍数为`q = (m-1) // k`。 
6. 对于每个`i`从`1`到`q`,`t = i * k`贡献`(m - t)`有效对。 总结这些贡献。 
7. 使用算术级数计算总和：

 答案变成：`sum_{i=1..q} (m - i*k) = q*m - k * (q*(q+1)//2)`。 
8. 输出测试用例的该值。 

### 为什么它有效

 整个变换依赖于将原始同余还原为可整除条件`t`。 一旦重写为`w | t(d-1)`，除了之间的gcd交互之外，原始日历的所有结构都消失了`w`和`d-1`。 这确保每个有效对通过其唯一差异被精确计数一次`t`，并且每个无效对都被排除，因为它的差异不满足模约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from math import gcd

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        m, d, w = map(int, input().split())
        a = d - 1
        g = gcd(w, a)
        k = w // g

        if k > m - 1:
            out.append("0")
            continue

        q = (m - 1) // k
        ans = q * m - k * (q * (q + 1) // 2)
        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现直接反映了代数约简。 唯一重要的变换是用基于 gcd 的步长替换模块化条件`k`。 一旦计算出来，剩下的就是所有有效差异贡献的封闭形式总和。 

必须小心`m - 1`，因为月份差异不能超过该界限。 另一个微妙之处是自始至终都使用整数运算； 使用 Python 的大整数时，所有中间值都可以轻松地适合 64 位整数，但在其他语言中，溢出管理至关重要。

 ## 边缘情况

 关键的边缘情况发生在以下情况：`d = 1`。 然后`d - 1 = 0`，所以每一项`t(d-1)`为零且模条件始终成立。 该算法处理这个问题是因为`g = gcd(w, 0) = w`， 所以`k = 1`。 每个差异都是有效的，公式简化为计算所有对`(x, y)`，即`m(m-1)/2`。 

另一个边缘情况是当`w = 1`。 一周只有一天，因此所有工作日都是相同的。 再次`k = 1`，并且算法正确地计算所有对。 

什么时候`m = 1`，没有有效的对。 公式得出`(m-1) = 0`， 所以`q = 0`结果是`0`。 

最后，当`k > m - 1`，不存在有效差异。 这对应于极其严格的模块化结构，即使最小的月份间隙也无法满足条件。 提前返回可确保我们不会尝试无效求和。
