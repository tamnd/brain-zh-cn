 ## 解决方案
 ## 问题理解

 给定一个整数数组，我们想要确定是否可以使用恰好 K 个交换操作将其转换为相反的形式。 交换操作交换数组中任意两个位置的值。 

自然的目标是了解使数组与其反转版本相同所需的最小交换次数，然后推断我们是否可以向上调整操作数以精确匹配 K，同时仍以正确的最终状态结束。 

关键的观察结果是反转结构将索引 i 与索引 n − 1 − i 配对。 每个这样的对最终必须具有相等的值，数组才能在交换后成为回文，因此问题简化为使用交换来修复不匹配的镜像对。 

未明确提供约束，但此类典型的 Codeforces 问题涉及最多 10^5 个元素的数组。 这立即意味着任何尝试模拟交换或搜索操作序列的解决方案都是不可能的。 该解决方案必须将问题减少到数组上的少量算术或计数操作。 

一些边缘情况在结构上很重要。 

例如，如果所有元素都已经对称`[1, 2, 3, 2, 1]`，最小交换次数为零。 总是假设需要交换的天真的方法会错误地多算。 

如果存在重复项，例如`[1, 1, 1, 1]`，交换对称位置可能不会执行任何操作，这会更改所需的最少操作。 

如果 K 小于所需的最小交换量，即使我们可以任意重新安排操作，答案也一定是不可能的。 

## 方法

 强力解释将是显式模拟对反转数组的转换。 人们可以尝试将每个位置 i 与其目标位置 n − 1 − i 匹配，并在发现不匹配时贪婪地执行交换。 虽然这正确地构造了一系列交换，但它变得低效，因为每个交换可能需要搜索正确的元素，从而在最坏的情况下导致 O(n^2) 行为。 

关键的见解是我们实际上不需要构建交换序列。 我们只需要两条信息：达到相反配置所需的最小交换数量X，以及是否可以在不改变最终结果的情况下插入额外的交换。 

该阵列分解为镜像对 (i, n − 1 − i)。 如果一对已经包含相同的值，则该对不需要交换。 否则，我们将其视为做出了一项必要的修正。 这给出了接近 ⌊n/2⌋ 的基线 X，当对称对匹配时向下调整。 

一旦知道了 X，剩下的问题就是如何精确地达到 K 次交换。 

如果数组没有重复项，则每次交换都会对配置产生明显的影响。 任何额外的交换都必须稍后撤消以保留最终状态，因此额外的操作成对出现，迫使 K − X 为偶数。 

如果存在重复项，我们可以在相等元素之间执行交换，而无需更改数组。 这使我们能够不受限制地吸收超出 X 的任何数量的额外掉期。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 掉期的贪心模拟 | O(n^2) | O(n^2) | O(n) | 太慢了|
 | 配对计数 + 奇偶校验推理 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 ### 1. 计算镜像对并检测重复项

 我们从两端迭代数组，比较位置 i 和 n − 1 − i。 如果值不同，则该对将贡献掉期的基本数量 X。同时，我们跟踪是否有任何值出现多次，因为这将决定我们是否可以“隐藏”额外的掉期。 

此步骤之所以有效，是因为每次交换最多可以修复最佳结构中的一个镜像不匹配。 

### 2. 计算所需的最低掉期 X

 我们将 X 初始化为⌊n/2⌋，因为每一对都对应于一个潜在的不匹配。 对于每个已经匹配的对称对，我们将 X 减一，因为那里不需要交换。 

这给出了实际需要校正的确切数量。 

### 3. 检查可行性条件 K ≥ X

 如果 K 小于 X，我们立即断定这是不可能的。 即使最佳交换也无法将操作数量减少到修复不匹配所需的结构最低限度以下。 

### 4. 处理重复与非重复的情况

 如果所有元素都是不同的，则每次交换都会改变结构，因此额外的交换必须抵消。 每个“执行和撤消”循环需要两次交换，因此 K − X 必须是偶数。 

如果存在重复项，我们可以在相等的值之间自由地执行交换，而不会影响数组，这意味着可以吸收任何额外数量的交换。 

### 为什么它有效

 该算法依赖于以下不变量：在修复所有不匹配的镜像对之后，阵列被唯一确定直到相同值的排列。 当所有值都不同时，任何交换都会修改排列状态，因此返回到相同的配置需要配对交换。 当存在重复项时，就存在非恒等排列，这些排列在数组状态上充当无操作，从而允许任意填充操作。 这将问题分为结构下限和仅取决于值重复的灵活性条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    x = n // 2
    
    for i in range(n // 2):
        if a[i] == a[n - 1 - i]:
            x -= 1
    
    # check duplicates
    seen = set()
    has_dup = False
    for v in a:
        if v in seen:
            has_dup = True
        seen.add(v)
    
    if k < x:
        print("NO")
        return
    
    if has_dup:
        print("YES")
    else:
        print("YES" if (k - x) % 2 == 0 else "NO")

if __name__ == "__main__":
    solve()
```实现直接遵循算法结构。 镜像对循环通过修正 n/2 的朴素上限来计算最小交换次数。 重复检测是使用一个集合在线性时间内完成的，这已经足够了，因为我们只需要一个布尔标志，而不是计数。 

最终的决定分为两种概念情况：对于重复项，额外的交换总是可以吸收的； 如果没有重复项，奇偶校验约束强制只有多余的交换计数才有效。

输出：否

 这演示了不存在重复项时的奇偶校验限制。

 ## 边缘情况

 ### 所有元素相同

 输入：`[7, 7, 7, 7]`每个镜像对都匹配，因此 X = 0。重复标志为 true，因此接受任何 K。 只要可行性 K ≥ 0 成立，无论 K 是多少，算法都会正确输出 YES。 

### 具有奇数额外交换的完全不同的数组

 输入：`[1, 2, 3, 4]`，K = 3

 我们计算 X = 2。由于没有重复项，我们要求 K − X 为偶数。 这里是 1，所以算法拒绝。 这避免了在保留结构的同时“浪费”单个交换的无效尝试，而如果不破坏并恢复成对的配置，这是不可能的。 

### 已经反转回文

 输入：`[1, 3, 3, 1]`X 变为 0，因为所有镜像对都匹配。 如果存在重复项，则任何 K 都是有效的。 如果没有重复项，则只有 K 有效，因为我们必须在取消对中添加交换。
