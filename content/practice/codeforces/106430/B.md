## Solution
## Problem Understanding

We have a number `X`并想把它变成另一个数字`Y`. One operation chooses a positive integer `M` and rounds `X` to the closest multiple of `M`。 如果两个倍数同样接近，则选择较大的倍数。 任务是找到变换所需的最少操作数`X`进入`Y`。 

关键的困难在于舍入操作不允许我们移动任意数量。 的选择`M`控制可能的下一个值，因此解决方案取决于了解一项操作的最大可能进度。 

约束允许非常大的值`X`和`Y`，因此模拟许多小的变化是不可行的。 如果一个值可能大到数十亿或更多，则采用一种反复将其减一或尝试所有可能的方法`M`值将需要太多的操作。 我们需要对数观察，因为每个有用的操作都必须显着改变数字的大小。 

主要的边缘情况来自小值附近的行为以及舍入中的平局规则。 

如果起始值已经是目标值，则无需进行任何操作。```
Input:
5 5
```正确的输出是：```
0
```总是先输入递增或递减逻辑的解决方案可能会错误地计算出不必要的操作。 

另一个边缘情况是数字不能再减少。 例如：```
Input:
3 1
```数量`3`不能向下舍入为`1`。 选择`M = 2`使`3`同样接近于`2`和`4`，领带向上，产生`4`。 选择较小的值`M`也无法产生`1`。 正确的输出是：```
-1
```重复应用最大减少公式而不检查小值的贪婪实现可能会永远循环或产生无效答案。 

当当前值小于目标值的两倍时，出现最终边界情况。```
Input:
10 6
```选择`M = 6`回合`10`到`6`， 因为`10`更接近于`6`比`12`。 答案是：```
1
```仅考虑两次增长或收缩的幂的解决方案将错过这些最后的一步转换。 

## 方法

 直接的暴力解决方案将尝试每个可能的值`M`在每一步中，模拟舍入操作，并搜索最短路径`X`到`Y`。 这是正确的，因为每一个合法的举动都经过探索。 然而，它是不可用的，因为可能有大量的选择`M`，以及之间的状态数`X`和`Y`也可以很大。 对于大约的值`10^18`，探索状态或尝试所有选择是不可能的。 

有用的观察来自于分别观察增加和减少。 

什么时候`X < Y`，一次操作最多可以将值增加两倍。 选择`M = 2X`回合`X`向上至`2X`，因为两个最接近的倍数是`0`和`2X`。 这意味着我们可以重复加倍，直到目标足够接近，然后选择`M = Y`最后一步。 操作次数正是所需的加倍次数，即`ceil(log2(Y / X))`。 

减少的情况是更微妙的情况。 减少`X`，我们需要选择一个`M < X`。 如果`X`位于之间`M`和`2M`，舍入后的值变为`M`什么时候`X`更接近于`M`比`2M`。 

减少的边界是：```
X - M < 2M - X
```这给出：```
M > 2X / 3
```最小有效值`M`产生最大的下降，所以最好的移动是：```
M = floor(2X / 3) + 1
```重复此操作会将值缩小大约一个因子`2/3`。 一旦当前值变得小于两倍`Y`，最后一个操作`M = Y`达到目标。 

蛮力之所以有效，是因为它探索了所有可能的舍入选择，但由于搜索空间巨大而失败。 观察到每个最佳移动都可以被最大有用的增加或减少所取代，从而将问题简化为一个简短的贪婪过程。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(状态数 × 可能的 M 值) | O(状态数) | 太慢了|
 | 最佳| O(log(最大(X, Y))) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.如果`X`已经等于`Y`， 返回`0`因为不需要任何操作。 
2.如果`X < Y`, 反复加倍`X`而加倍则未达到目标。 每次加倍都是通过选择来实现的`M = 2X`，所以这始终是一个有效的操作。 
3. 倍增阶段后，执行最后一个操作`M = Y`。 由于当前值现在大于`Y / 2`，四舍五入到最接近的倍数`Y`准确地产生`Y`。 
4. 如果`X > Y`,首先检查当前值是否已经小于`2Y`。 如果是，则执行一项操作`M = Y`得出答案。 
5.否则，重复更换`X`和`floor(2X / 3) + 1`。 这是尽可能快的下降，但仍然保持结果为正。 
6. 计算这些减少，直到当前值小于`2Y`，然后添加一个最终操作直接舍入为`Y`。 
7. 如果该值无法减小并且仍然大于`Y`，报告说转变是不可能的。 

为什么有效：每个有用的操作对其值的改变程度都有限制。 增加时，加倍是最大可能的跳跃，因为舍入不能使数字增加超过其本身的大小。 减小时，可达到的最小正舍入值为`floor(2X/3)+1`，任何其他选择都会使数字至少一样大。 由于每次贪婪移动都会取得最大可能的进展，因此没有其他序列可以通过更少的操作达到目标。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(x, y):
    if x == y:
        return 0

    ans = 0

    if x < y:
        while x * 2 <= y:
            x *= 2
            ans += 1
        return ans + 1

    if x <= 3:
        return -1

    while x >= 2 * y:
        x = (2 * x) // 3 + 1
        ans += 1
        if x <= 3 and x > y:
            return -1

    return ans + 1

def main():
    data = list(map(int, sys.stdin.read().split()))
    if not data:
        return

    t = data[0]
    idx = 1
    out = []

    for _ in range(t):
        x = data[idx]
        y = data[idx + 1]
        idx += 2
        out.append(str(solve_case(x, y)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```功能`solve_case`分离两个方向，因为增加和减少有不同的最佳移动。 

递增分支使用乘以二而不是对数计算。 这避免了浮点精度问题并直接对执行的操作进行计数。 

递减分支使用整数算术`floor(2X/3)+1`。 操作顺序在这里很重要。 计算`2 * x // 3 + 1`准确地保持下限行为，而浮点计算可能会失去大输入的精度。 

条件`x >= 2 * y`确定是否可以进行最终的直接舍入。 一旦这是假的，`M = Y`有效是因为`X`更接近于`Y`比`2Y`。

 ## 边缘情况

 对于`X = Y`，算法立即返回零，因为状态已经正确。 这可以避免进入贪婪分支并防止计算不必要的操作。 

为了`X = 3`和`Y = 1`，算法检测到`X`太小而无法执行有用的减少。 可能的舍入选择无法创建`1`，所以返回`-1`是正确的。 

为了`X = 10`和`Y = 6`，该算法发现`10 < 2 * 6`，因此它跳过了缩减阶段。 选择`M = 6`回合`10`到`6`，这确认了最后一步的条件。 

对于非常大的值，例如`X = 10^12`和`Y = 1`，该算法从不迭代单个数字。 它仅执行几何约简，保持运算计数对数。
