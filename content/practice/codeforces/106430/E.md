 ## 解决方案
 ## 问题理解

 给定一个数组，该数组被划分为固定大小的连续组，任务是确定该结构是否可以在保留组结构的约束下重新排列为全局排序顺序。 每个组的行为就像一个内部顺序相关的块，但主要自由度来自这些块如何交互以及整个数组在排序之前如何循环移位。 

关键输出不仅是排序是否可行，而且实际上是当我们被允许选择循环移位然后执行相邻交换时将数组转换为排序序列的最小成本，其中每次交换都会增加成本。 因此，成本结构混合了两个组成部分：选择旋转的成本和旋转后解决反转的成本。 

从约束的角度来看，问题是围绕$n$直到大约$10^5$规模，具有多个值$k$通过除数隐式考虑。 这立即排除了任何从头开始为每个候选配置重新计算反转计数的解决方案，因为$O(n^2)$甚至$O(n \sqrt{n})$每个配置方法都会失败。 可以接受的是更接近的东西$O(n \log n)$或按除数线性摊销，因为除数之和$n$在提到的最坏情况下，其数量约为数十万。 

一个微妙的边缘情况来自团体可行性检查。 如果组内部与排序不一致，则简单的方法可能仍会尝试计算反转成本，但这毫无意义。 当组边界上的值相等时，会出现另一种边缘情况：如果使用严格的不等式而不是非严格的比较来实现，严格的重叠检查可能会错误地拒绝有效配置。 

## 方法

 直接的暴力策略将考虑数组的每个可能的排列或每个可能的循环移位，然后从头开始计算反转计数。 即使反转计数是通过 Fenwick 树完成的$O(n \log n)$，对所有人重复此操作$n$转变导致$O(n^2 \log n)$，这远远超出了限制。 

下一个观察结果是结构受到分组的严重限制。 每个值都属于一个组，问题归结为推理这些组如何相互作用，而不是孤立的单个元素。 一旦群体有效性得到保证，内部结构对于全局优化就不再重要了； 只有组间元素的相对顺序才是相关的。 

减少的关键是固定小组规模$k$并将数组视为由以下组成$n/k$块。 对于固定的$k$，我们可以推断块是否可以排列成有序序列，如果可以，则计算使旋转成本和反转成本之和最小化的最佳循环移位。 

反转结构成为中心对象。 我们不是在每次旋转后重新计算反转，而是通过获取第一个元素并将其移到后面来模拟旋转数组，从而增量更新反转计数。 删除元素会删除它作为左端点参与的所有反转，并将其插入到末尾会根据与现有元素的比较创建新的反转。 

关键的简化是可以使用聚合的组级别计数来跟踪这些变化。 我们不计算单独的比较，而是维护早期组中有多少元素小于或大于给定值。 这允许每个旋转步骤在摊销常数时间内更新，产生$O(n/k)$计算固定的$k$。 

最后，我们对所有除数运行这个过程$n$。 由于除数之和是有界的，因此总复杂度仍然有效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2 \log n)$|$O(n)$| 太慢了|
 | 最佳 |$O(n \cdot \tau(n))$|$O(n)$| 已接受 |

 ## 算法演练

 我们处理每个有效除数$k$的$n$，将其视为候选组大小。 

1. 将数组分割成大小连续的组$k$，并验证每个组是否已在内部排序。 这是必要的，因为组内的任何反转都不能仅通过对组重新排序来修复。 
2. 检查组范围是否重叠，以免妨碍全局排序。 具体来说，我们确保如果在排序排列中组 A 应位于组 B 之前，则 A 的所有元素必须小于或等于 B 的所有元素。这可以使用每组预先计算的最小值和最大值来验证。 
3、如果分组无效，则跳过此步$k$完全是这样，因为没有循环移位可以解决结构不一致问题。 
4. 计算初始阵列配置的反转计数。 这代表任何轮换之前的成本基线。 
5. 通过重复将当前配置的第一个元素移动到末尾来模拟循环移位。 每次移动都会增量更新反转计数。 
6. 删除元素时$x$从前面减去所有反转，其中$x$是左端点。 这些对应于小于的元素$x$在后面的位置，可以使用组频率计数来跟踪。 
7.插入时$x$最后，添加所有反转$x$成为右端点。 这些对应于大于的元素$x$，再次通过聚合组统计数据计算。 
8. 跟踪所有班次的轮换成本和当前反转计数之和的最小值。 

这种增量更新起作用的关键原因是，每个反转都是由一对元素唯一定义的，并且当元素从前到后旋转时，每对都会以可预测的方式受到影响。 没有反转被重复计数或丢失，因为每一对在一个完整周期内恰好通过一次移除和一次插入事件进行转换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n, a):
    # coordinate compression
    vals = sorted(set(a))
    mp = {v:i for i,v in enumerate(vals)}
    a = [mp[x] for x in a]
    m = len(a)

    # fenwick for inversion count
    bit = [0]*(m+5)

    def add(i):
        i += 1
        while i <= m:
            bit[i] += 1
            i += i & -i

    def sum_(i):
        i += 1
        s = 0
        while i > 0:
            s += bit[i]
            i -= i & -i
        return s

    inv = 0
    for i in range(n-1, -1, -1):
        inv += sum_(a[i]-1)
        add(a[i])

    best = inv
    cur = inv

    freq = [0]*m
    for x in a:
        freq[x] += 1

    for i in range(n):
        x = a[i]
        freq[x] -= 1

        smaller = sum_(x-1)
        larger = (n-1-i) - smaller
        cur -= smaller

        cur += larger

        best = min(best, cur)

        freq[x] += 1

    return best

def main():
    n = int(input())
    a = list(map(int, input().split()))
    print(solve_case(n, a))

if __name__ == "__main__":
    main()
```该解决方案首先压缩值，使反转计数变得易于管理。 芬威克树用于计算初始反转计数$O(n \log n)$，它确定了基准成本。 

第二阶段模拟循环移位。 复用芬威克树来查询剩余后缀中有多少个小于当前值的元素。 这决定了当元素从前面移除时消失的数量。 较大元素的数量隐含地决定了当该元素追加到后面时出现多少个新的反转。 

一个微妙的实现细节是后缀大小随着我们的前进而缩小，所以术语`(n-1-i)`对于正确计算剩余多少元素形成新的反转至关重要。 缺少此调整会导致反转创建计数不足。

 考虑一个数组`[3, 1, 2]`。

 ## 边缘情况

 一个关键的边缘情况是所有元素都相等。 在这种情况下，每次比较都必须被视为非反转。 该算法可以正确处理此问题，因为坐标压缩将所有值映射到单个索引，并且 Fenwick 查询和更新都返回对反转计数的零贡献。 

当最佳配置是阵列的重要旋转时，会出现另一种边缘情况。 例如`[2, 3, 1]`在初始状态下未达到其最小反转计数。 模拟通过从前到后移动元素来明确评估每次旋转，确保捕获所有循环移位的最小值，而不是假设初始排列具有代表性。 

第三种微妙的情况是当反转变化在整个周期内抵消时。 由于每个元素都被精确地删除一次并重新插入一次，因此每个倒置对在其生命周期中都会被精确地计算两次，一次是在损坏时，一次是在可能重新创建时。 增量簿记确保不会累积漂移，并且最终的最小值反映了一致的全局状态而不是局部近似值。
