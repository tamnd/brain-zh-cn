 ## 解决方案
 ## 问题理解

 该任务可以看作是在 XOR 值的约束系统上工作，但约束不是直接用边和节点来编写的。 相反，它们源自对数组段的操作，可以将其重新解释为图形问题。 

我们从一个类似数组的结构开始，其中每个操作都使用 XOR 修改一个连续的段。 关键的观察是段操作可以转换为对数组的差异表示的约束。 一旦我们切换到差异数组，每个操作仅影响两个位置，这意味着每个操作变成恰好两个变量之间的关系。 

经过此转换后，我们最终得到一个类似图形的结构，其中每个位置都有所需的 XOR 值，并且每条边对应于一个操作，该操作分配一个对两个端点都有贡献的值。 问题变成为边缘分配值，以便对于每个节点，事件边缘值的 XOR 与给定目标匹配。 

输出要么是满足所有节点约束的边权重的完整分配，要么是不存在分配的声明。 

这些约束意味着我们至少需要在节点和边的数量上进行线性时间处理。 任何涉及尝试所有分配或迭代边子集的解决方案都是立即不可能的，因为可能性的数量随着边的数量呈指数增长。 即使尝试按节点独立求解系统的方法也会失败，因为边耦合了图上的约束。 

当连接的组件具有非零的节点值异或和时，就会出现微妙的边缘情况。 例如，如果组件中的三个节点的值为 1、2 和 4，则它们的 XOR 为 7，该值不为零。 在这种情况下，任何分配都无法同时满足所有约束，因为每条边都对两个节点有贡献，这意味着跨组件的总异或必须始终抵消。 忽略此全局条件的简单求解器可能仍会尝试构建并产生不一致的结果。 

当图不是树时，会出现另一种故障模式。 如果存在循环并且我们不仔细选择构造策略，则在重新访问边时任意分配可能会产生矛盾。 这就是为什么像生成树这样的结构化分解是必不可少的。 

## 方法

 直接尝试会将每条边视为变量，并尝试分配同时满足所有节点 XOR 方程的值。 这成为域 GF(2) 上的线性方程组，但以 XOR 形式编写。 理论上，直接使用高斯消元法求解是可行的。 然而，图结构使得更简单的构造成为可能。 

暴力破解的视角是对边进行一一赋值，最后检查是否满足所有节点约束。 这需要尝试边权重的组合，在最坏的情况下，边权重会随着边的数量呈指数增长。 即使我们限制从节点要求导出的值，本地决策也可能将不一致传播到图中，迫使回溯。 

关键的结构见解是每条边恰好贡献两次，每个端点一次。 这意味着在任何连接的组件内，所有节点值的异或必须为零。 一旦这个条件成立，我们就可以停止用任意图来思考，而是将结构简化为生成树，因为除了一致性之外，循环不提供额外的自由度。

在树上，我们可以从叶子向上解决问题。 叶节点恰好有一个关联边，因此其所需的异或直接决定了该边的值。 一旦该边缘被固定，我们就可以移除叶子并将其影响传播到其邻居。 重复此过程可以消除所有歧义，并确保每个约束都满足一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分配 | 指数| O(n + m) | 太慢了|
 | 基于树的叶子消除| O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 根据输入构建节点和边图，将每条边解释为连接两个节点的约束。 每个节点都带有所需的 XOR 值，该值必须等于关联边权重的 XOR。 
2. 对于每个连接的组件，计算所有节点值的 XOR。 如果此 XOR 非零，则立即断定该组件不存在有效分配。 这是因为每条边都对两个节点有贡献，因此所有贡献总共抵消。 
3. 如果组件有效，则提取该组件的任意生成树。 这将结构简化为一种形式，其中除根之外的每个节点都恰好有一个父边，通过该父边可以解决其约束。 
4. 任意生成生成树的根并维护一组叶子。 叶子是当前树结构中度数为 1 的节点。 
5. 重复取出一个不是根的叶子节点，读取其当前所需的异或值，并将该值指定为其唯一关联边的权重。 此分配可确保立即满足叶子的约束。 
6. 分配边后，从树中删除叶子，并通过将其值异或到邻居的要求中，将其值传播到邻居。 这保持了正确性，因为删除的边先前对两个端点都有贡献。 
7. 继续此过程，直到只剩下根。 此时，全局异或条件保证自动满足根的要求。 

### 为什么它有效

 该构造保持一个不变量：在每一步，每个剩余节点的 XOR 要求等于仍需要由剩余子树中未处理的边提供的 XOR 贡献。 移除一片叶子仅使用一个自由度来解决一个约束，并且传播步骤保留了剩余结构的一致性。 由于每条边都只处理一次，并且每个节点约束也只考虑一次，因此在初始可行性检查后不会出现矛盾。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    val = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    edges = []
    
    for i in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, i))
        g[v].append((u, i))
        edges.append((u, v))
    
    vis = [False] * n
    ans = [0] * m
    
    from collections import deque
    
    for s in range(n):
        if vis[s]:
            continue
        
        # gather component
        comp = []
        stack = [s]
        vis[s] = True
        
        while stack:
            u = stack.pop()
            comp.append(u)
            for v, _ in g[u]:
                if not vis[v]:
                    vis[v] = True
                    stack.append(v)
        
        # check XOR condition
        x = 0
        for u in comp:
            x ^= val[u]
        
        if x != 0:
            print("NO")
            return
        
        # build parent structure via BFS tree
        parent = [-1] * n
        parent_edge = [-1] * n
        order = []
        
        dq = deque([s])
        parent[s] = s
        
        while dq:
            u = dq.popleft()
            order.append(u)
            for v, ei in g[u]:
                if parent[v] == -1:
                    parent[v] = u
                    parent_edge[v] = ei
                    dq.append(v)
        
        # process in reverse BFS (leaf-like removal)
        for u in reversed(order):
            if u == s:
                continue
            p = parent[u]
            ei = parent_edge[u]
            ans[ei] = val[u]
            val[p] ^= val[u]
        
        # root handled automatically
    
    print("YES")
    print(*ans)

if __name__ == "__main__":
    solve()
```该代码首先将图分解为连接的组件。 对于每个组件，它验证节点值的 XOR 必须为零的必要条件。 如果失败，该函数会提前终止。 

确认可行性后，构建以任意节点为根的 BFS 生成树。 父数组对树结构进行编码，其中每个节点（根除外）恰好有一个父边，该父边将用于分配其边权重。 

反向 BFS 顺序模拟叶子去除。 每个节点的值都分配给将其连接到其父节点的边，这会立即满足该节点的要求。 然后使用 XOR 向上传播其值，更新父级的要求。 

一个微妙的细节是我们修改`val`就位。 这是至关重要的，因为它会在处理子项时积累剩余需求。 如果没有这种传播，父节点将无法正确反映剩余的约束。 

## 工作示例

 ### 示例 1

 考虑一个链中具有三个节点的小组件。 

初始节点值：`[3, 5, 6]`边缘：`1-2`,`2-3`| 步骤| 节点已处理 | 边缘分配 | 使用价值| 家长更新 |
 | --- | --- | --- | --- | --- |
 | 1 | 3 | (2,3) | 6 | val[2] ^= 6 |
 | 2 | 2 | (1,2) | 更新了 val[2] | val[1] ^= val[2] | val[1] ^= val[2] |

 处理完节点3后，边(2,3)固定为6，节点2的要求变为`5 XOR 6 = 3`。 然后节点 2 分配边 (1,2) = 3，节点 1 变得一致。 

这显示了叶子消除如何自然地解决自下而上的约束。 

### 示例 2

 星形图，中心节点为 1，叶节点为 2、3、4。 

节点值：`[0, 1, 2, 3]`| 步骤| 节点已处理 | 边缘分配 | 使用价值| 家长更新 |
 | --- | --- | --- | --- | --- |
 | 1 | 4 | (1,4) | 3 | val[1] ^= 3 |
 | 2 | 3 | (1,3) | 2 | val[1] ^= 2 |
 | 3 | 2 | (1,2) | 1 | val[1] ^= 1 |

 最后，由于初始异或一致性，中心节点自动变为零，确认正确性。

 ## 边缘情况

 一种边缘情况是完全断开的图，其中每个节点都是隔离的。 在这种情况下，每个节点形成其自己的组件，并且XOR条件很容易得到满足。 该算法独立处理每个节点，不分配边，并立即返回成功。 

另一种情况是组件是单周期的。 BFS 生成树恰好从环中删除一条边，将其变成一棵树。 删除的循环边缘对于正确性来说不是必需的，因为基于叶的重建已经保证了生成树上的一致性。 

最后一种情况是所有节点值都为零。 BFS 仍然运行，但每个分配的边接收零权重，并且传播使所有值保持不变。 输出仍然有效，因为每个节点都满足 XOR 约束。
