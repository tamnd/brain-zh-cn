 ## 解决方案
 ## 问题理解

 我们得到一个仅由左括号和右括号组成的字符串。 任务是在去掉除括号之外的所有内容后确定该序列是否可以从某些有效的算术表达式中产生。 

一个关键的观察是，任何算术表达式，一旦删除数字和运算符，就只留下括号强加的结构。 当每个右括号与之前打开的括号匹配时，该结构完全有效，并且没有任何前缀关闭的括号数量多于已打开的括号数量。 

因此，输入只是一个候选括号结构，输出是一个二元决策：该结构是否可以对应于正确形成的表达式。 

约束 n 高达 200000 立即排除任何二次模拟或重复重新扫描。 任何尝试通过搜索或重复修改字符串来匹配对的解决方案都会太慢。 线性扫描是唯一现实的选择。 

一些边缘情况暴露了常见的错误。 

如果字符串以右括号开头，例如 input`")("`，不可能将其解释为来自任何有效的表达式，因为没有更早的上下文可以提供匹配的左括号。 正确的输出是`NO`。 

如果字符串的总计数正确但排序无效，例如`"())("`，打开的总数等于关闭的总数，但在某些前缀处该序列变得无效。 正确的输出仍然是`NO`，这表明仅平衡是不够的。 

如果弦完全平衡，就像`"(())()"`，排序和计数都对齐，答案是`YES`。 

## 方法

 验证结构的一种强力方法是重复搜索相邻的匹配对`"()"`并将它们移除，直到无法再移除为止。 如果字符串变为空，则它是有效的。 

这是有效的，因为每个有效的括号对最终都必须匹配并删除。 然而，每次删除都可能会移动字符串并强制重新扫描。 在最坏的情况下，比如`"((((....))))"`，每次删除都会再次扫描几乎整个字符串。 当 n 达到 200000 时，这会导致大约 O(n^2) 次操作，这太慢了。 

关键的结构见解是，有效性仅取决于从左到右阅读时我们是否遇到比可用空洞更多的右括号。 我们不模拟删除，而是维护一个计数器，表示每个步骤存在多少个不匹配的左括号。 

每当我们看到`'('`，我们增加计数器。 每当我们看到`')'`，我们必须至少有一个无法匹配的`'('`可用的; 否则该序列立即无效。 最后，仅当不存在未匹配的空缺时，该序列才有效。 

这将问题转化为单次传递，每个角色需要不断地工作。

 ## 算法演练

 我们从左到右扫描字符串，同时跟踪表示当前打开但不匹配的括号数量的单个整数。 

1.初始化一个计数器`balance = 0`。 这代表了多少`'('`已经看到尚未匹配的`')'`。 
2. 迭代字符串中的每个字符。 
3. 如果角色是`'('`, 增量`balance`一个。 这反映出引入了一种新的无与伦比的左括号。 
4.如果角色是`')'`, 递减`balance`一个。 在递减之前或之后，我们必须确保`balance`还不是零，因为这意味着我们正在尝试关闭一个不存在的括号。 如果发生这种情况，该序列将无法对应于任何有效的表达式。 
5. 如果在任何时候`balance`变为负数，立即断定该序列无效。 
6. 处理完整个字符串后，检查是否`balance`等于零。 如果是，则每个左括号都已匹配； 否则有些仍然不匹配并且序列无效。 

正确性取决于以下事实：在任何前缀处，右括号的数量不能超过任何有效表达式中左括号的数量。 

### 为什么它有效

 该算法保持一个不变量：处理完每个前缀后，`balance`等于该前缀中不匹配的左括号的数量（假设该前缀到目前为止有效）。 每个`'('`引入了新的无与伦比的要求，并且每个`')'`正好删除了一项这样的要求。 如果在不存在要求的情况下出现右括号，则它违反了格式良好的括号的基本配对约束，使得整个序列不可能从任何有效表达式派生。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    balance = 0

    for ch in s:
        if ch == '(':
            balance += 1
        else:
            balance -= 1
            if balance < 0:
                print("NO")
                return

    print("YES" if balance == 0 else "NO")

if __name__ == "__main__":
    solve()
```该实现镜像了前面描述的线性扫描。 提前退出时`balance`变为负数至关重要，因为进一步继续无法修复已经无效的前缀。 最终的相等性检查确保不存在不匹配的左括号。 

一个微妙的点是我们永远不需要显式存储括号的位置或尝试配对。 计数器对必要的结构进行了完全编码。

 ## 边缘情况

 一种重要的边缘情况是序列以右括号开始。 用于输入`")("`，算法立即将第一个字符处的余额降低到零以下。 由于没有看到左括号，这反映了一个不可能的结构，并且输出是正确的`NO`。 

另一种情况是左括号和右括号的总数相等，但排序无效，例如`"())("`。 余额中途回到零，但随后降至零以下。 该算法在违规发生的确切时间点检测违规行为，而不是依赖最终计数。 

第三种情况是一长串仅由左括号组成的序列，例如`"((((("`。 余额永远不会变成负数，但最终仍保持正数。 这表明有效性要求前缀正确性和完全匹配，而最终的零检查满足了这一要求。
