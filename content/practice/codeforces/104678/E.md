 ## 解决方案
 ## 问题理解

 有$n$团队，每个团队都以固定的力量值开始。 每对球队只打一场比赛，因此比赛是完全循环赛。 比赛的结果仅取决于最终的实力：较强的球队获胜，如果双方实力相等，则比赛为平局。 

每场比赛都会奖励积分，一支球队的总成绩就是所有比赛的总成绩。 获胜者获得 3 分，平局则获得 1 分。 我们可以在每次训练中将任意一支队伍的实力增加 1，并且每次训练只影响一支队伍。 

关键目标不是直接选择比赛结果，而是调整实力，以便在所有训练结束后，所有球队的积分总和尽可能大。 在实现这一最大可能总数的所有可能方法中，我们必须找到所需的最少培训课程数。 

约束表明$n$可以大到 200000，所以任何解决方案都必须粗略地$O(n \log n)$或更好。 对所有成对的团队采用二次方法是不可能的，因为有$O(n^2)$比赛数量太多，甚至无法模拟。 

当许多团队拥有相同的实力时，就会出现一个微妙的问题。 例如，如果几支球队的积分相等，那么它们之间的所有比赛都是平局，这会减少总积分。 增加优势可以打破联系，但这样做会同时影响多个配对结果，因此贪婪的局部决策需要仔细论证。 

一个幼稚的错误是尝试模拟比赛或一对一地调整实力。 但这会失败，因为一个增量会同时改变与所有其他球队的比较，而不仅仅是一个对手。 

举个具体的例子，如果所有球队都从实力开始$[5, 5, 5]$，每场比赛都是平局，产生最少的总分。 增加一支球队会同时稍微改变其所有比赛，因此问题根本在于全局结构，而不是个人比赛操纵。 

## 方法

 我们先来了解一下总分由什么决定。 每对球队若胜者得 3 分，若平局则得 2 分。 由于匹配数固定为$\frac{n(n-1)}{2}$，最大化总得分相当于最大化非平局比赛的数量。 

当两支球队最终实力相等时，一场比赛就是平局。 这意味着最佳情况是所有最终优势都不同，因为这样每场比赛都有获胜者，并且贡献 3 分而不是 2 分。因此，目标简化为消除最终优势数组中的所有重复项。 

我们只能增加价值，而不能减少价值。 所以任务就变成了：从数组开始$a$，为每个元素分配一个整数增量，以便生成的数组$b$满足$b_1 < b_2 < \dots < b_n$，同时最小化总增量$\sum (b_i - a_i)$。 这是排序数组上的经典贪心构造问题。 

蛮力的想法是尝试在团队之间分配增量的所有可能方法，直到所有值都不同，并计算成本。 这是不可行的，因为每个元素都可以任意增长，并且状态空间呈指数爆炸。 即使尝试在本地解决冲突也可能会引发进一步的冲突，从而导致最坏的情况$O(\text{range of values})$每次调整。 

关键的观察结果是排序后，结构变成线性的。 每个元素只需比前一个最终值至少多 1 即可避免相等。 一旦固定了早期的选择，当前元素的最佳选择就被强制：它应该尽可能小，同时尊重其原始值和严格的增加约束。 这消除了所有回溯并产生单遍解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了|
 | 最优贪心 |$O(n \log n)$| O(1) 额外 | 已接受 |

 ## 算法演练

 ### 步骤

 1. 按非降序对优势数组进行排序。 

排序是必要的，因为我们想要的最终条件（严格增加值）最容易按顺序执行。 
2. 初始化运行变量`current`跟踪下一支球队的最小有效值。 
3. 按排序顺序处理每个团队。 对于每一个原始强度$a_i$，将其最终强度设置为$b_i = \max(a_i, current)$。 

这确保了我们永远不会减少价值，也不会违反之前团队的顺序。 
4. 分配后$b_i$， 更新`current`到$b_i + 1$，因为下一个元素必须严格更大。 
5. 将成本累计为$\sum (b_i - a_i)$，代表培训课程的总数。 

### 为什么它有效

 在每个位置，我们都会为当前团队强制执行尽可能小的有效值。 任何更大的选择只会增加成本，而不会提高可行性，因为未来元素的唯一限制是严格大于前一个元素。 这创建了一个单调结构：一旦一个值被固定，它就成为所有后续值的下限。 由于在完全捕获未来可行性的约束下，每个步骤都是局部最小的，因此任何后续调整都不可能使早期决策变得次优。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    current = a[0]
    ans = 0

    for i in range(n):
        if i == 0:
            current = a[0]
        else:
            current = max(a[i], current + 1)
        ans += current - a[i]

    print(ans)

if __name__ == "__main__":
    solve()
```排序步骤是将所有对之间的原始组合相互作用转换为线性约束链。 不排序的话，依赖结构不清楚，但是排序之后，每个元素只依赖于之前构造的值。 

这`current`变量编码避免与所有早期元素相等的最小允许值。 这`max`运营确保我们既尊重原有实力，又严格增长要求。 累积差异直接计算所有团队应用了多少增量。 

一个常见的实现陷阱是忘记一旦值增加，它就会影响所有后续约束，而不仅仅是相邻元素。 另一个是错误地初始化第一个元素，因为它不需要大于它之前的任何元素。

 ## 边缘情况

 一个关键的边缘情况是所有优势都相等。 在这种情况下，每个成对匹配最初都是平局，算法必须将值推入严格递增的序列。 贪心方法自然地通过转动来处理这个问题$[x, x, x, \dots]$进入$[x, x+1, x+2, \dots]$，累积增量的三角形数。 每个步骤仅取决于先前选择的值，因此不会出现歧义。 

另一种边缘情况是数组已经严格递增。 排序后，每$a_i$已经满足$a_i > a_{i-1}$，所以`max`操作总是选择$a_i$本身。 成本保持为零，因为不需要训练，并且算法正确地避免了不必要的增量。 

当重复项与大间隙交错时，会出现最后一种微妙的情况，例如$[1,1,100]$。 第二个元素仅被推至 2，而较大的第三个元素保持不变，因为它已经满足递增约束。 这表明该算法绝不会过度调整超出维持严格排序所需的值。
