 ## 问题理解

 两个观察者站在相反的两极，数出从各自位置可见的星星。 每颗恒星都只能从一个极点看到，而不能从两个极点看到，这意味着这两次观测将整组恒星分成了两个不相交的组。 一个观察者报告计数 A，另一个观察者报告计数 B。任务是恢复恒星的总数，这只是这两个不相交集合的并集的大小。 

输入 A 和 B 以整数形式给出，但它们可能非常大，每个最多 100,000 位。 这立即排除了任何依赖标准固定宽度整数类型的方法，因为即使 128 位算术也太小了。 时间限制允许对位数进行线性时间处理，因此扫描每个数字恒定次数的操作是可以接受的，而任何位数的二次方都会太慢。 

如果假设内置整数解析在所有环境中都是安全的而不考虑语言限制，则会出现一种微妙的失败情况。 在某些语言或简单的实现中，将这些数字转换为本机类型会悄无声息地溢出或完全失败。 如果尝试连接或按数字操作而没有正确处理不同的长度，则会出现另一个问题，因为 A 和 B 不一定具有相同的位数。 

一个具体的边缘场景是 A 和 B 的大小相差很大。 例如，A 可以是 1 位数字，B 可以是 100,000 位数字。 任何基于对齐的算术都必须正确处理较短数字中丢失的前导数字。 另一种情况是，两个数字都很大，并且它们的和产生额外的进位，使数字长度增加 1，例如 999...999 加 1。 

## 方法

 对这个问题的直接解释表明我们只是将两个不相交的计数组合在一起，因此答案是 A + B。简单的方法是将两个数字解析为整数并使用内置算术将它们相加。 从概念上讲，这是可行的，因为 Python 和其他一些语言支持任意精度整数，但在更严格的环境或 C++ 等语言中，这会因溢出而失败。 

即使在Python中，虽然直接整数加法是正确的，但问题的设计是为了强调对大数算术的理解，而不是盲目依赖类型。 如果我们假设一种没有大整数的语言，那么在反转两个字符串后，暴力策略就变成了数字加法。 这将从最低有效位到最高有效位处理每个数字，并手动进行溢出。 

暴力数字模拟在数字数量上以线性时间运行，考虑到我们必须至少读取每个数字一次，这是最佳的。 除了将数字视为以 10 为基数的表示形式并按列求和之外，没有任何结构可利用。 

关键的观察结果是星集是不相交的，因此不存在包含排除复杂性，没有重叠校正，也没有隐藏约束。 整个任务简化为任意精度加法。

 ## 算法演练

 我们将两个输入字符串视为以 10 为基数的数字，并从右到左执行标准加法。

1. 读取字符串 A 和 B。它们表示可能长达 100,000 位的十进制数字。 
2. 在每个字符串的最后一位初始化两个指针，并将进位值设置为零。 指针代表每个数字中正在处理的当前数字位置。 
3. 将A 和B 中的相应数字与进位重复相加。 如果一个字符串已被完全消耗，则将其数字视为零。 这可确保两个数字从最低有效侧正确对齐。 
4. 将结果数字计算为模 10 的余数，并将进位更新为整数除以 10。将结果数字附加到临时缓冲区。 
5. 继续，直到两个数字中的所有数字都已处理完毕并且没有进位剩余。 
6. 反转缓冲区以获得正确顺序的最终总和。 

此过程有效的原因是位置十进制表示允许独立的按列加法，进位仅传播到下一个更高的数字。 在每一步中，部分结果都正确地表示两个数字的后缀加上传入进位之和，因此算法保持的不变性是所有处理的低位数字都被完全解析并且不会受到未来操作的影响。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a = input().strip()
    b = input().strip()
    
    i, j = len(a) - 1, len(b) - 1
    carry = 0
    res = []
    
    while i >= 0 or j >= 0 or carry:
        x = ord(a[i]) - 48 if i >= 0 else 0
        y = ord(b[j]) - 48 if j >= 0 else 0
        
        s = x + y + carry
        res.append(chr((s % 10) + 48))
        carry = s // 10
        
        i -= 1
        j -= 1
    
    res.reverse()
    sys.stdout.write("".join(res))

if __name__ == "__main__":
    solve()
```该实现使用 ASCII 算术执行手动数字提取，以避免字符串到整数转换的开销。 循环继续，直到两个索引都用完并且没有进位剩余，即使最终和使位数增加一位，这也确保了正确性。 需要在末尾反转，因为数字是按照从最低有效位到最高有效位的顺序附加的。 

一个常见的错误是当两个指针都达到零时停止循环，忽略剩余的进位，例如 999 + 1，这会错误地删除前导数字。

 ## 边缘情况

 关键的边缘情况是一个或两个输入为零时。 该算法自然地处理这个问题，因为一旦索引超出范围，数字提取就会返回零，并且不需要特殊的分支。 

另一种情况是最后的进位创建一个新的最高有效数字。 在像 999 + 1 这样的情况下，循环在两个索引都用完后继续，确保进位作为新数字附加而不是被丢弃。 最后的逆转然后将其正确地放在前面。 

不等长度的输入被统一处理，因为该算法从不假设对齐位置。 一旦一个指针变为负值，相应的数字贡献将被视为零，这无需预处理或填充即可保持正确性。
