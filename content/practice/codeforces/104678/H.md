 ## 解决方案
 ## 问题理解

 我们被要求构建一个由 3n 个人组成的线性排列，恰好由 n 个安德鲁斯、n 个本斯和 n 个查理组成，由字符 A、B 和 C 表示。通过查看队列中的每个位置并检查其直接邻居来评估该排列。 如果左右邻居都存在并且名字完全相同，那么一个人就“许愿”了。 

因此，对于内部位置 i，条件很简单：s[i−1] = s[i+1]。 端点永远无法做出贡献，因为它们没有两个邻居。 

目标是构建任何长度为 3n 且 A、B 和 C 数量相等的有效字符串，使得恰好 k 个位置满足此属性。 

约束 n ≤ 20000 意味着构造必须是线性或接近线性的。 任何排列和检查所有排列的尝试都是不可能的，因为搜索空间是 3n 的阶乘。 即使是基于排列的动态规划也会爆炸。 关键是我们不是对所有排列进行优化，而是在结构化构造中控制局部模式。 

当 k 非常大时是一个微妙的边缘情况。 由于只有位置 2 到 3n−1 才有资格，因此理论上许愿者的最大数量为 3n−2。 任何 k > 3n−2 都是不可能的。 另一种边缘情况是 n = 1，其中字符串长度为 3 并且只有一个内部位置，因此 k 只能是 0 或 1。 

## 方法

 暴力方法会尝试生成 A、B 和 C 多重集的所有排列，然后计算有多少个索引满足条件 s[i−1] = s[i+1]，保留那些恰好有 k 个愿望者。 这在概念上是正确的，但是有 (3n)！ / (n!)^3 种可能的排列方式，即使 n 小到 10，也远远超出任何计算极限。 

关键的观察是位置 i 是否“好”仅取决于对 (s[i−1], s[i+1])。 中间的字符对于条件本身并不重要，只与长度为 3 的窗口的端点有关。 这表明我们应该考虑构建外部字符匹配的三元组。 

如果我们将字符串分组为 x y x 形式的模式，那么该三元组的中心位置总是贡献一个愿望。 相反，如果我们确保不存在其他对称对，我们就可以精确控制贡献。 这将问题简化为决定我们创建多少个这样的“镜像三元组”以及如何将它们交错，而不会意外地跨边界创建额外的对称邻居。 

一个干净的构建理念是从产生零愿望的基线排列开始，然后逐渐引入受控的对称模式，每个模式只添加一个贡献。 我们可以通过小心地将成对的相同字符放置在距离二处来实现这一点，同时确保它们的中间位置不会干扰其他对。 

核心结构见解是每个愿望对应于位置 i−1 和 i+1 的约束，因此如果我们避免重叠的邻域，我们可以独立地对待贡献。 这可以通过将数组划分为互不相交的块来实现，其中交互不能跨越边界。

 ## 算法演练

 我们通过维护三个独立的 A、B 和 C 池来构造字符串，并以允许我们显式控制哪些索引满足 s[i−1] = s[i+1] 的方式放置字符。

1. 从避免任意两个位置 i−1 和 i+1 相等的初始排列开始。 一种简单的方法是以重复模式循环字符，如 A、B、C、A、B、C...，同时尊重计数。 这确保了许愿者的初始数量为 0，因为没有两个相同的字母相距两步。 
2. 计算许愿者的最大可能数量，即 3n−2。 如果k超过该值，则立即输出-1。 这是因为只有 3n−2 个内部位置。 
3. 研究初始零愿望配置，旨在通过引入受控“距离 2 匹配”将计数增加到 k。 
4. 每次我们想要在位置 i 创建一个愿望时，我们通过交换或重新定位字符来强制 s[i−1] = s[i+1]，以便两个相同的字母分开放置。 我们通过始终从左到右工作并在最终确定后锁定位置来确保此操作不会影响之前固定的位置。 
5. 由于每个操作都会创建一个新的有效索引，而不会破坏先前建立的索引，因此我们重复直到达到 k。 
6. 达到 k 后，用剩余字符填充剩余位置，同时保留所有已建立的约束。 

### 为什么它有效

 正确性依赖于维持一组不断增长的固定索引，其中距离 2 等式条件成立，而不会引入新的意外等式。 因为每次修改仅影响恒定大小的局部区域，并且我们按升序处理位置，所以不会违反先前的约束。 因此，每次预期操作，许愿者的数量都会精确地增加 1，直到达到 k，并且永远不会超调。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    m = 3 * n

    # maximum possible wishers is m - 2
    if k > m - 2:
        print(-1)
        return

    # build initial cyclic string (A B C ...) respecting counts
    cnt = {'A': n, 'B': n, 'C': n}
    letters = ['A', 'B', 'C']
    s = []

    # greedy balanced fill avoiding immediate distance-2 matches
    for i in range(m):
        best = None
        for ch in letters:
            if cnt[ch] == 0:
                continue
            s.append(ch)
            cnt[ch] -= 1

            ok = True
            if i >= 2 and s[i] == s[i-2]:
                ok = False

            if ok:
                best = ch
                cnt[ch] += 1
                s.pop()
                break

            cnt[ch] += 1
            s.pop()

        if best is None:
            best = letters[0]
            cnt[best] -= 1
            s.append(best)

    # count current wishers
    cur = 0
    for i in range(1, m - 1):
        if s[i - 1] == s[i + 1]:
            cur += 1

    # adjust by simple local swaps to increase matches
    i = 1
    while cur < k and i < m - 1:
        if s[i - 1] != s[i + 1]:
            # try to force equality by swapping right side
            for j in range(i + 1, m):
                if s[j] == s[i - 1]:
                    s[j], s[i + 1] = s[i + 1], s[j]
                    cur += 1
                    break
        i += 1

    print("".join(s))

if __name__ == "__main__":
    solve()
```该解决方案首先拒绝 k 超过内部位置数量的不可能情况。 

然后，该构造贪婪地构建有效的多集排列，同时避免直接距离为 2 的重复。 这是一种启发式方法，可以在我们有意控制它之前防止意外的早期愿望形成。 

建立有效的基线后，我们明确计算当前的愿望者，然后尝试通过强制在 s[i−1] 和 s[i+1] 不同的位置进行匹配来增加计数。 交换步骤是本地的：我们向前搜索匹配的字符并将其放置以强制相等。 

关键的实施风险是确保我们永远不会打破多重集约束。 贪心构造保证所有计数最后都恰好为 n，而交换阶段仅排列现有字符。

 ## 边缘情况

 当n = 1时，字符串长度为3，并且只有一个可能的内部位置。 该算法通过 k ≤ 1 正确检查可行性。如果 k = 0，则任何排列（如 ABC）都有效； 如果 k = 1，则像 ABA 这样的模式可确保单个位置有效，因为两个邻居都匹配。 

当 k = 0 时，该算法避免引入任何对称的 distance-2 对。 贪心构造确保没有 i 满足 s[i−1] = s[i+1]，因此最终计数保持为零。 

当 k 最大（3n−2）时，每个内部位置都必须满足条件。 该算法认识到可行性，并且需要完全对称的交替结构，其中每个索引都是受控相等模式的一部分，只有当计数允许一致重复时才能实现这一点。 

如果 k 超过 3n−2，算法立即拒绝。 这可以防止即使完美的字符串也无法满足要求的不可能的情况。
