 ## 解决方案
 ## 问题理解

 数轴上的两个点各有一只蚂蚁。 每只蚂蚁从已知的坐标开始，以恒定但未知的速度和方向移动。 关于每只蚂蚁运动的唯一信息是它从哪里开始以及在固定时间后它会在哪里。 

由此，任务是确定两只蚂蚁是否在同一时刻占据同一位置。 如果存在这样的时刻，我们必须计算这种情况发生的最早时间。 

关键细节是“t秒后蚂蚁到达位置p”完全决定了它的运动。 这意味着均匀的线性运动，因此每只蚂蚁的位置随着时间的直线函数而变化。 

约束足够小，所有计算都可以在恒定时间内完成。 每只蚂蚁都由几个整数来描述，所有整数的范围约为一万个。 这排除了随着时间的推移进行模拟的任何需要。 相反，问题简化为求解简单的线性方程组。 浮点运算就足够了，因为最终答案只需要达到百万分之一的精度。 

当两只蚂蚁以相同的速度移动时，就会出现一个微妙的问题。 在这种情况下，它们的相对距离永远不会改变。 如果他们尚未处于相同的起始位置，他们将永远不会相遇。 另一个极端情况是计算的会议时间为负时，这对应于时间零之前发生的交叉点，因此无关紧要。 

## 方法

 暴力方法将以较小的时间增量模拟两只蚂蚁，更新它们的位置并在每一步检查是否相等。 由于速度是恒定的，位置会线性变化，但简单的模拟需要迭代可能大量的时间步长才能准确检测交汇点。 即使步长很细，也会出现精度问题，并且如果会议时间过长或不合理，最坏情况下的步数将无限增长。 

问题的结构使得模拟变得不必要。 每只蚂蚁都遵循时间的线性函数。 从输入中我们可以直接恢复它的速度。 一旦知道了两个速度，问题就简化为寻找一维中两条线的交点。 如果将来存在这种交叉点，那就是解决方案。 

核心观察是，我们不随时间跟踪位置，而是直接求解两个线性函数变得相等的时间。 这将问题转换为单个代数方程。

 | --- | --- | --- | --- |
 | 暴力模拟| O(T)| O(1) | O(1) | 太慢/不可靠 |
 | 代数解 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将每只蚂蚁的运动建模为时间的线性函数。 如果一只蚂蚁从位置 a 开始，并在 t 秒后到达位置 p，则其速度为 (p − a) / t。 

我们计算两个速度，然后求解位置匹配的时间。 

1. 计算第一只蚂蚁的速度为 v1 = (p1 − a1) / t1。 这捕获了第一只蚂蚁移动的速度和方向。 
2. 出于同样的原因，计算第二只蚂蚁的速度为 v2 = (p2 − a2) / t2。 
3. 如果 v1 和 v2 实际上相等，则两只蚂蚁以恒定的间隔平行移动。 在这种情况下，他们永远不会见面，因为他们最初的立场不同。 
4. 否则，建立方程 a1 + v1 * t = a2 + v2 * t 并求解 t。 
5. 重新排列得出 t = (a2 − a1) / (v1 − v2)。 这是唯一的候选人见面时间。 
6. 如果计算出的 t 为负，则丢弃它，因为它代表过去的交集。 
7. 否则，输出t作为最早的会议时间。 

### 为什么它有效

每只蚂蚁的位置都是时间的线性函数，因此运动系统在时间位置平面上形成两条直线。 两条不同的线最多相交一次。 计算速度将每个运动描述转换为斜截形式。 求解这些线性函数的相等性可以准确地确定交点。 如果斜率相等，则线是平行的，因此除非它们处处重合，否则不会发生相交，这在这里是不可能的，因为起始位置不同。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a1, t1, p1 = map(int, input().split())
    a2, t2, p2 = map(int, input().split())

    v1 = (p1 - a1) / t1
    v2 = (p2 - a2) / t2

    # parallel motion
    if abs(v1 - v2) < 1e-12:
        print(-1)
        return

    t = (a2 - a1) / (v1 - v2)

    if t < 0:
        print(-1)
    else:
        print(f"{t:.10f}")

if __name__ == "__main__":
    solve()
```实现直接遵循导出的方程。 首先计算速度，并且所有内容都保持浮点形式，因为该问题允许较小的数值容差。 相等速度的比较使用 epsilon 而不是精确相等，因为除法可能会引入较小的舍入差异。 

仅在确认分母实际上不为零后才应用 t 的公式。 最后，我们确保只接受非负时间。 

## 工作示例

 ### 示例 1

 输入：```

```对于第一只蚂蚁，速度为 (5 − (−3)) / 2 = 4。对于第二只蚂蚁，速度为 (10 − 12) / 1 = −2。 

我们求解交叉时间。 

| 步骤| 价值|
 | --- | --- |
 | v1 | 4 |
 | v2 | -2 |
 | t 计算 | (12 − (−3)) / (4 − (−2)) | (12 − (−3)) / (4 − (−2)) |
 | t | 15 / 6 = 2.5 | 15 / 6 = 2.5

 输出：```
2.50000000
```这证实了蚂蚁开始时是分开的，但向一个共同点移动并在 2.5 秒后相遇。

 ## 边缘情况

 一种重要的情况是两只蚂蚁以完全相同的速度移动。 例如：```
0 1 10
5 1 15
```这里两者都以每秒 10 个单位的速度向同一方向移动。 该算法计算出 v1 = v2 并立即拒绝会议。 这是正确的，因为它们之间的距离永远保持不变。 

另一种情况是计算的交集位于过去。 考虑：```
0 1 10
10 1 0
```如果解释不正确，根据公式计算出的会议时间将为负数，但算法会显式检查 t < 0 并将其丢弃。 这对应于在时间零之前相交的线，这在问题中描述的物理过程之外。 

最后，当速度非常接近时，可能会出现浮动精度问题。 epsilon 比较可防止将几乎平行的运动错误分类为相交，从而确保边界情况下的稳定性。
