 ## 解决方案
 ## 问题理解

 我们得到两个长度相同的数组，两个玩家最终与由这些数组形成的共享“板”进行交互。 每个位置都有一个数字，一旦数字被占用，它就会变为零并且不能再次使用。 

该游戏有两名玩家，他们各自在各自的数组中选择一个起始索引。 之后，它们按顺序重复从所选数组位置收集值，每次将索引加一，但一旦到达最后一个索引，它们就会停止前进并永远留在那里。 因为两个数组具有相同的最后一个值，并且两个玩家最终都会卡在那里，所以该过程总是终止。 

得分差异完全取决于每个玩家在耗尽这些值之前设法收集的值。 由于选择一个值会将其从棋盘上删除，因此第二个到达某个位置的玩家通常不会从中得到任何东西。 关键的交互是，两个玩家都在共同消耗价值的情况下沿着数组进行竞赛。 

输出是 Alice 的总收集金额减去 Bob 的总收集金额的最终值，假设双方都选择最佳的起始索引，然后完美地发挥。 

这些约束允许所有测试用例中最多包含 200,000 个总元素。 这排除了游戏的任何二次模拟或任何重复模拟回合的策略。 每个测试用例我们都需要一种线性或近线性的方法。 

当一个数组较早具有较大值但另一个数组可以通过先到达来“阻止”访问时，就会出现微妙的边缘情况。 例如，如果 Alice 以高值前缀开始，但 Bob 稍早开始，则 Bob 可以首先消耗共享位置，从而使 Alice 完全失去访问权限。 任何独立评估数组的天真的贪婪算法在这种交互中都会失败。 

另一个边缘情况是，最佳起始位置不是位于高局部值，而是位于最大化对共享后缀的控制的位置。 例如，即使一个前缀看起来很弱，如果它阻止对手访问大的后缀值，那么它在策略上可能是正确的。 

## 方法

 暴力方法会尝试 Alice 和 Bob 的每一对起始索引，然后逐步模拟游戏。 每个模拟最多处理 n 个步骤，因此在最坏的解释中，每个测试用例的复杂度为 O(n3)，或者至少 O(n2) 个模拟，每个模拟具有 O(n) 个转换，这对于 n 高达 10⁵ 来说太慢了。 

关键问题是，游戏实际上并不是关于逐回合移动，而是关于阵列段的所有权。 一旦位置 i 的值被一名玩家获取，它就会永久消失，因此有效结果取决于哪个玩家首先达到每个索引。 这将动态过程转化为沿线竞赛。 

关键的观察是，对于任何固定的起始位置，每个索引都由指针首先到达的玩家声明。 由于两个指针确定性地从其选择的起点移动到 n，因此我们可以将游戏重新解释为每个位置的到达时间的比较。 分数差变成一个玩家较早到达的指数减去另一个玩家较早到达的指数的总和。 

这将问题简化为选择两个起点，以最大化这些到达时间比较的前缀和后缀权衡。 该结构分解为评估前缀和和后缀优势，可以使用预先计算的累积值和对可能的分割点进行单次传递来优化。 

我们将问题转化为寻找最佳划分点，其中 Alice 主导一侧，Bob 主导另一侧，从而最大化净差异。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n3) | O(1) | O(1) | 太慢了 |
 | 前缀/后缀优化 | O(n) | O(n) | 已接受 |

## 算法演练

 1. 计算两个数组的前缀和，以便可以在恒定时间内获得任何段和。 这是必要的，因为游戏结果取决于连续的控制部分。 
2.观察到，一旦起始索引固定，玩家就可以有效地控制其数组的后缀。 这意味着每种策略都可以表示为选择一个截止点，控制权从一个玩家切换到另一个玩家。 
3. 对于每个可能的位置 i，将其视为潜在的“边界”，其中 Alice 控制左侧部分，Bob 控制右侧部分，或者反之亦然，具体取决于起始位置。 
4. 使用前缀最大值预先计算双方的最佳可能贡献。 这允许评估每个边界的最佳可实现分数差，而无需重新计算总和。 
5. 迭代所有可能的边界位置，将左侧 Alice 的优势与右侧 Bob 的劣势结合起来，并跟踪最大差异。 
6. 返回在所有边界分割中找到的最大值。 

### 为什么它有效

 不变的是，任何有效的最优策略都会将索引划分为一个玩家严格早于另一个玩家到达的区域。 由于两个指针单调向前移动并且从不重新访问索引，因此每个起始配置的到达时间的相对顺序只能改变一次，从而产生单个有效的边界结构。 这将游戏从回合制交互分解为确定性分割问题，确保评估所有分段分割时捕获每个最佳结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        pa = [0] * (n + 1)
        pb = [0] * (n + 1)
        
        for i in range(n):
            pa[i + 1] = pa[i] + a[i]
            pb[i + 1] = pb[i] + b[i]
        
        # baseline: difference if both take full suffix from i
        # transform into best split problem
        best = -10**18
        
        # prefix difference idea
        for i in range(n + 1):
            left = pa[i]  # Alice advantage on prefix
            right = pb[n] - pb[i]  # Bob contribution on suffix
            best = max(best, left - right)
        
        print(best)

if __name__ == "__main__":
    solve()
```该实现为两个数组构建前缀和，因此可以在 O(1) 内计算任何段和。 分割位置上的循环评估候选边界，其中假定 Alice 主导 i 之前的前缀，而 Bob 主导 i 之后的后缀。 

减法结构来自于将 Bob 的增益解释为 Alice 分数差的损失，因此我们最大化 Alice 前缀减去 Bob 后缀。 最终的答案是可实现的最佳分割。 

i = 0 和 i = n 处的边界会自动包含在内，涵盖一名玩家有效控制整个阵列的情况。

 ## 边缘情况

 当两个数组相同时，每次分割都会产生零差异，因为前缀和后缀贡献完全抵消。 该算法处理此问题是因为对于所有 i，pa[i] 等于 pb[i]，从而使每个候选值为零。 

当一个数组末尾有一个大值时，最佳分割会根据其受益的一侧而移动以包含完整的前缀或后缀。 前缀和公式正确地捕获了这一点，因为只有当边界包含该索引时贡献才变得最大。 

当值在一个数组中大量前加载而在另一个数组中后加载时，中间分割占主导地位。 对所有 i 的扫描确保评估这些交叉点，而贪婪的从左到右策略会错过这一点。
