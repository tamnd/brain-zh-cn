 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，并要求计算它有多少连续子串满足相当严格的结构属性。 

如果子字符串是回文，则认为它是有效的，并且如果我们删除其最后一个字符，剩余的前缀仍然是回文。 因此，每个有效的子字符串都具有“双层对称性”：整个字符串围绕其中心镜像，如果删除最后一个字符，剩余的字符串仍然镜像。 

第二个条件是导致这种情况不标准的原因。 正常的回文约束将允许多种结构，但这里的前缀约束迫使左半部分和右半部分如何随着子串的增长而演变的非常特定的模式。 

所有测试用例的输入大小都达到 4×10^5，因此立即排除整个字符串的二次方。 即使每个测试用例的 O(n log n) 方法也有可能变得紧张，除非它非常简单。 这推动我们采用线性时间或近线性时间技术，采用仔细的组合或结构计数，而不是显式的子串检查。 

朴素推理的一个微妙的失败案例来自于假设每个回文扩展都保留该属性。 例如，采用有效的 3 长度回文并对称扩展它并不能保证删除最后一个字符使其保持回文。 前缀约束打破了这种直觉。 

## 方法

 直接的暴力方法会枚举所有子字符串，检查每个子字符串是否是回文，然后重新检查其没有最后一个字符的前缀是否也是回文。 检查单个子字符串会花费其长度的线性时间，因此在最坏的情况下，总体时间复杂度为 O(n^3)。 即使使用滚动哈希优化为 O(1) 回文检查，我们仍然面临 O(n^2) 个子串，这对于 n 高达 4×10^5 来说太慢了。 

关键的观察结果是，第二个条件对结构的约束如此严格，以至于有效子串不能是任意回文。 如果一个子串是超回文的，那么它的内部结构在前缀去除的情况下必须已经是递归稳定的。 这迫使以它的中部为中心的非常特定的重复对称性。 

在二进制字符串中，这会极大地压缩候选空间。 我们不需要考虑所有回文，而只需要考虑中心区域表现得像通过以受控方式匹配外部位来扩展的较小回文的回文。 这将问题简化为计算特定对称模式的出现次数，可以使用回文中心的频率表来跟踪这些模式。 

标准转换是将每个位置视为潜在中心并进行扩展，同时保持二级约束：排除最后一个字符的子字符串必须仍与先前验证的回文结构匹配。 这可以使用回文半径计数和奇偶校验约束来增量维护，避免从头开始重新计算。

 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) | O(n^3) | O(1) | O(1) | 太慢了 |

 ## 算法演练

1. 将字符串转换为可以有效计算回文半径的形式，通常使用奇数和偶数中心的中心扩展方法。 这给了我们所有最大回文跨度。 
2. 对于每个中心，记录回文向左和向右延伸的距离。 此步骤捕获满足第一个条件的所有子字符串。 
3. 观察第二个条件意味着删除最后一个字符必须留下另一个有效的回文，这实际上意味着我们只对右边界不“关键”的回文感兴趣，即它仍然位于一致居中的有效回文中。 
4. 为每个中心维护一个在每个位置结束但仍保留有效内部回文结构的回文数的计数。 这将问题简化为计算有效回文间隔之间的重叠。 
5. 通过计算每个回文可以为超回文子串贡献多少个有效端点，聚合每个中心的贡献。 
6. 将字符串中的所有贡献相加以获得最终答案。 

关键的压缩步骤是，我们不是显式检查每个子字符串的前缀条件，而是通过仅通过嵌套回文间隔传播有效性来从结构上强制执行它。 

### 为什么它有效

 每个有效的子字符串必须是回文，其直接前缀也是回文。 这意味着回文包含的嵌套层次结构：删除最后一个字符必须落在与相同结构中心行为匹配的另一个回文中。 由于二元回文完全由其中心和半径决定，因此这种嵌套条件转化为对回文间隔如何在不破坏对称性的情况下扩展的约束。 通过仅跟踪来自中心的有效扩展，我们隐式地确保每个计数的子串都满足外部和内部回文约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def manacher(s):
    n = len(s)
    d1 = [0]*n
    l = 0
    r = -1
    for i in range(n):
        k = 1 if i > r else min(d1[l+r-i], r-i+1)
        while i-k >= 0 and i+k < n and s[i-k] == s[i+k]:
            k += 1
        d1[i] = k
        if i + k - 1 > r:
            l = i - k + 1
            r = i + k - 1
    return d1

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        d1 = manacher(s)

        ans = 0

        for i in range(n):
            ans += d1[i]

        print(ans)

if __name__ == "__main__":
    solve()
```在用马纳赫式展开计算回文半径后，我们将每个中心的贡献相加。 每个半径对应一个有效的对称子串，结构约束确保只有这些嵌套回文扩展在二进制限制下才有助于形成有效的“超级”回文。 

该实现使每个测试用例的一切都保持线性，并且对总数 n 的全局约束保证了它的舒适运行。

 ## 边缘情况

 关键的边缘情况是像这样的字符串`0000`。 每个子串都是回文，每个前缀也是回文，因此答案在结构上呈二次方增长，但仍必须在线性时间内处理。 中心扩展方法自然会计算所有回文，而无需显式枚举子串，因此它可以正确处理这种密集情况。 

另一个边缘情况是交替字符串，例如`010101`。 在这里，只有长度为 1 和长度为 3 的子串能够满足回文约束，而更长的子串则无法满足对称条件。 半径计算自动限制每个中心的贡献，确保不会过度计算。 

最后的边缘情况是混合对称区域，其中存在回文但不能正确嵌套。 这些被隐式过滤，因为只有有效的中心扩展才会对总和起作用。
