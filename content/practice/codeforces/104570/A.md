 ## 问题理解

 我们得到一个由三种硬币类型组成的小型“货币系统”：价值 1 的硬币、价值 10 的硬币和价值 100 的硬币。对于每个测试用例，我们知道每种类型有多少硬币可用，并且我们想要确定是否可以选择这些硬币的某些子集，以便它们的总价值恰好等于目标数量。 

每个测试用例都是独立的。 我们不需要最小化或最大化任何东西，只需决定形成精确总和的可行性。 

约束很大：最多 100,000 个测试用例，每个参数可以大到 1e9。 这立即排除了任何试图枚举硬币组合或模拟所有可能性的解决方案。 即使是超过计数的三重嵌套循环也是不可能的，因为最坏的情况将是 1e27 次操作。 

值的结构是关键：1、10 和 100 是 10 的幂。 这强烈暗示了一种贪婪的逐位构造，因为较高的面额只会影响较高的小数位，并且不能通过超出有限范围的较低面额来补偿。 

当独立对待硬币而不尊重其等级制度时，就会出现一个幼稚的错误。 例如，尝试首先用 100 个硬币贪婪地满足总和，而不用 10 个硬币和 1 个硬币检查剩余可行性，可能会失败。 

一个简单的边缘情况说明了这一点：

 输入：```
a = 9, b = 0, c = 1, n = 10
```这里我们可以用1个10币（不可用）或者用10个1币加1个100币减调整逻辑来组成10，但实际上我们不能减去硬币。 粗心贪婪地选择先拿 100 个硬币会错误地假设可行性。 

正确答案是：```
NO
```因为我们无法将 100 个硬币“分解”成超出其固定贡献的更小的值。 

核心困难是正确处理关卡之间的交互，同时尊重硬币限制。 

## 方法

 暴力方法会尝试所有可能的 100 个硬币、10 个硬币和 1 个硬币的计数。 对于 x 100 个硬币、y 10 个硬币和 z 1 个硬币的每个选择，我们将检查是否：

 x * 100 + y * 10 + z = n

 约束条件 x ≤ c、y ≤ b、z ≤ a。 

即使我们迭代 x、y、z 直到它们的极限，这也是 O(abc)，这是完全不可行的，因为每个都可以达到 1e9。 

关键的观察结果是，硬币系统的位置以 10 为基数。1 和 10 硬币完全控制总和的最后两位数字，而 100 硬币决定了上面的所有内容。 这意味着我们不需要搜索所有组合，只需贪婪地调整一级并修复其余部分。 

我们首先处理 100 个硬币。 我们尝试使用尽可能多的数量，但不超过 n // 100 且不超过 c。 一旦我们确定了这个选择，剩下的问题就减少到使用 10 和 1 个硬币形成余数。 这个减少的问题可以再次贪婪地解决：使用尽可能多的 10 个硬币，然后检查剩余价值是否适合可用的 1 个硬币。 

该结构确保高面额硬币的决策独立于低面额硬币的决策，因为较低面额的硬币无法弥补高面值硬币的短缺。

 ## 算法演练

 1. 在不超过目标或可用量的情况下，尝试使用尽可能多的 100 面值硬币。 我们计算 x = min(c, n // 100)。 此步骤确保我们不会使用高价值硬币超出目标。 
2. 从目标中减去他们的贡献：n 变为n − 100·x。 这隔离了必须使用较小硬币形成的剩余价值。 
3. 现在尝试类似地使用 10 面值的硬币：y = min(b, n // 10)。 这样可以最大限度地利用中型硬币，而不会超过剩余金额。 
4. 减去他们的贡献：n 变为 n − 10·y。 此时，只有 1 值的硬币是相关的。 
5. 检查剩余金额是否小于或等于可用1币数量。 如果是的话，这个数额是可以实现的； 否则是不可能的。 

### 为什么它有效

 正确性来自于以下事实：每种硬币类型都是下一个较小类型的 10 倍。这消除了跨级别权衡：使用更少的 100 个硬币永远不会有帮助，除非它增加了 10/1 范围内的可行性，但减少 100 个硬币只会将所需的余数增加 100 的倍数，而这无法通过超出已处理的模块约束的 10 或 1 个硬币来修复。 同样的推理适用于从 10 到 1。每一步都在移动到下一个数字位置之前完全饱和当前数字位置，确保不会错过最佳解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c, n = map(int, input().split())

        use_100 = min(c, n // 100)
        n -= use_100 * 100

        use_10 = min(b, n // 10)
        n -= use_10 * 10

        if n <= a:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```其实现完全按照所描述的那样进行贪婪归约。 唯一的微妙点是在每个面额步骤之后更新剩余价值； 这必须在转移到下一个硬币类型之前完成，否则以后的决定将基于过时的状态。 

所有算术都保持在安全整数范围内，并且每个测试用例都在恒定时间内处理，考虑到输入大小，这是必要的。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        a, b, c, n = map(int, input().split())
        use_100 = min(c, n // 100)
        n -= use_100 * 100

        use_10 = min(b, n // 10)
        n -= use_10 * 10

        out.append("YES" if n <= a else "NO")
    return "\n".join(out)

 ## 边缘情况

 一种微妙的情况是目标为零。 该算法立即减少所有面额并检查 n ≤ a，由于 n 为 0，因此该算法成立。即使不存在硬币，该算法也会正确返回 YES。 

另一种情况是更高面额的金额超出了潜在的组合。 因为我们总是用 min(available, n // value) 来限制使用量，所以我们永远不会减去超过必要的值，以防止出现负余数。 

第三种情况是最优解决方案使用比贪婪选择更少的高面额硬币。 这种情况不可能发生，因为购买更多高面值硬币永远不会降低低面额硬币的可行性； 它仅将剩余总和减少 100 或 10 的倍数，从而保留了剩余问题空间的可解性。
