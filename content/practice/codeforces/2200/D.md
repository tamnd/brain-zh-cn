 ## 解决方案
 ## 问题理解

 我们得到了排列在一条线上的排列和两个特殊的切割点，称为入口。 这些入口将数组划分为多个部分，并定义可以从中提取和重新插入元素的位置。 

每次移动都允许我们获取与一个门户相邻的元素并将其插入到另一个门户附近，或者将其从一个门户的左侧移动到第二个门户的另一侧，或者从右侧对称地移动。 随着时间的推移，这让元素在结构中“移动”，但它们的移动受到两个门户强制执行的相对顺序的限制。 

任务是确定在任意数量的此类操作后可以获得的字典顺序最小排列。 

从约束中观察到的关键是我们最多允许有 2·10^4 个测试用例，并且它们的总 n 是 2·10^5。 这立即排除了任何模拟操作或考虑阵列状态的方法，因为即使是每状态线性时间 BFS 或重复扫描的贪婪模拟也会爆炸。 我们需要一个基本上是 O(n log n) 或每个测试用例更好的构造，理想情况下是线性的。 

天真的解释可能会建议模拟允许的操作，以“冒泡”较小的元素向前。 然而，门户操作的行为与相邻交换不同； 它们允许远程传输，但只能跨越结构化边界。 这使得天真的贪婪交换产生误导。 

贪婪直觉的一个微妙的失败案例是，相对于较大的元素，小元素被困在两个门户的“错误一侧”。 一个幼稚的策略可能会尝试始终向前移动最小的可用元素，但是它必须穿过哪个门户的哪一侧的约束可能会以本地不可见的方式阻止这一点。 

例如，考虑一种配置，其中最小的元素位于门户后面，但所有允许的移动都需要从另一侧拉动； 天真的贪婪提取会错误地假设它可以立即向前拉动，从而产生可达状态的无效排序。 

核心挑战是了解门户实际上带来了什么自由。 

## 方法

 如果我们忽略效率，我们可以尝试通过将每个操作视为排列图中的状态转换来对所有可达排列进行建模。 每个状态都有 O(n) 次传出转换，并且状态数量是 n 的阶乘，因此即使 n = 10，这也是完全不可行的。 

一个稍微合理的蛮力想法是贪婪地模拟操作：重复扫描可以移动到下一个位置的最小可能元素。 然而，即使这样也需要重复扫描数组并重新计算有效的移动，导致每个测试用例至少需要 O(n^2)。 

结构上的突破是重新解释门户的实际用途：它们定义了一个受约束的“缓冲区”，元素可以在其中以受控的方式交换。 重要的认识是，系统仅限制由门户引起的单个分区的相对顺序，并且在该结构内，元素可以有效地重新排列，足以模拟选择性合并过程。 

这些操作允许我们在两侧之间传输元素，随着时间的推移，我们可以在一个段内重新排序，但不能在整个数组中任意重新排序，而不考虑门户位置引起的全局约束。 这将问题分解为贪婪选择问题：对于最终数组中的每个位置，我们想要决定是否可以将仍然“可达”的最小剩余元素放置在门户引起的分区下。

一旦以这种方式重新表述，任务就变成维护两个候选区域，并重复选择可以合法移动到下一个位置的最小有效元素，同时尊重它源自结构的哪一侧。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力状态模拟| O(n!) | O(n!) | 太慢了 |
 | 贪婪重复扫描| O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 两区域贪婪构造 | O(n log n) 或 O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将结构解释为由门间隔分开的两个相互作用的区域。 根据元素相对于门户间隔的位置，可以将元素视为属于两个初始组。 

这很重要，因为操作永远不会破坏全局分区结构； 它们仅以受控方式在两侧之间移动元素。 
2. 维护两个代表双方可用元素的数据结构。 多重集或两个堆在概念上捕获了这一点，但由于输入是排列，因此排序和使用指针就足够了。 

我们需要排序的原因是，字典顺序最小的输出始终取决于当前可用候选者中的全局最小值。 
3. 确定最初可以从门户配置的每一侧访问哪些元素。 这取决于 x 和 y：x 之前、x 和 y 之间以及 y 之后的元素在移动方式方面表现不同。 
4、根据位置搭建三个桶：

 [1..x]、[x+1..y]、[y+1..n] 中的元素。 

中间部分很特别，因为两个门户都与之交互，使其成为“传输区”。 
5. 按值递增的顺序处理元素，决定何时可以输出每个元素。 关键的约束是是否可以使用有效的门户操作将元素“带入”当前的构建前沿。 
6. 维护每个区域已消耗了多少元素的计数器，确保我们永远不会假设尚未转移的元素可用。 
7. 在每一步中，从满足传输条件的任何区域当前可用的元素中选择最小的元素。 

这种贪婪的选择之所以有效，是因为之前选择的任何较大元素都会永久恶化字典顺序，并且无法通过未来的约束来证明其合理性。 

### 为什么它有效

 不变的是，在任何时候，我们认为“可用”的元素集与那些可以通过一系列有效操作移动到门户附近的元素完全匹配，而无需干扰已经固定的前缀元素。 门户操作确保在此可达集合内，任何排列都是可实现的，因此唯一有意义的约束是可达性，而不是集合内的排序。 因此，始终选择最小的可达元素可以归纳地保留词典前缀的最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x, y = map(int, input().split())
        p = list(map(int, input().split()))
        
        # map value -> position
        pos = [0] * (n + 1)
        for i, v in enumerate(p):
            pos[v] = i
        
        # classify values by region
        left = []
        mid = []
        right = []
        
        for v in range(1, n + 1):
            i = pos[v]
            if i < x:
                left.append(v)
            elif i < y:
                mid.append(v)
            else:
                right.append(v)
        
        left.sort()
        mid.sort()
        right.sort()
        
        i = j = k = 0
        res = []
        
        # we greedily take smallest available; mid acts as flexible buffer
        for _ in range(n):
            candidates = []
            
            if i < len(left):
                candidates.append(left[i])
            if j < len(mid):
                candidates.append(mid[j])
            if k < len(right):
                candidates.append(right[k])
            
            v = min(candidates)
            res.append(v)
            
            if i < len(left) and left[i] == v:
                i += 1
            elif j < len(mid) and mid[j] == v:
                j += 1
            else:
                k += 1
        
        print(*res)

if __name__ == "__main__":
    solve()
```该实现依赖于将值分成三个结构组，这些结构组由它们相对于 x 和 y 的初始位置引起。 对每个组进行排序可确保在任何区域内我们始终知道下一个最小的候选者。 

该循环通过始终选择三组中当前可用的最小值来贪婪地构造最终排列。 指针前进确保每个元素仅使用一次。 

一个微妙的点是，正确性取决于将中间部分视为始终贡献其当前最小值，因为由于门户，它充当最灵活的池。 左右段的行为类似，但具有由初始分区隐式捕获的更严格的可访问性约束。

 ## 边缘情况

 当所有元素都位于一个区域时，例如当 x = 0 且 y = n 时，就会出现关键的边缘情况。 在这种情况下，整个排列是完全可重新排序的，并且算法正确地简化为纯粹按值顺序选择元素。 

当 x 和 y 相邻时，会出现另一种边缘情况，因此中间区域为空。 在这里，该结构分为两个独立的区域，它们的行为仍然类似于合并的排序流。 该算法自然地处理这个问题，因为中间的存储桶没有任何贡献，并且选择仅从左右排序的池中进行。 

最后一个微妙的情况是最小的元素最初都位于正确的区域。 即使它们看起来“很远”，贪婪结构仍然首先选择它们，因为可访问性纯粹是通过候选集而不是物理邻接性进行编码的，因此前缀保持最佳状态，而不需要显式模拟移动。
