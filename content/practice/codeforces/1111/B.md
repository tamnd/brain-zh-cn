 ## 解决方案
 ## 问题理解

 我们有一群超级英雄，每个英雄都有一个初始力量值。 我们可以使用两种类型的操作来修改这个组：我们可以从组中删除一个超级英雄（只要至少剩下两个），或者我们可以将所选超级英雄的力量增加一个。 操作总数存在全局限制，并且还有一个附加限制，即任何单个超级英雄只能增加有限的次数。 

目标是最终得到一些非空超级英雄子集，其平均功率在应用允许的操作后尽可能大。 

输出是表示最大可实现平均值的单个实数。 

这些限制立即表明$O(n^2)$或者对所有子集进行更糟糕的模拟是不可能的，因为$n$取决于$10^5$。 任何尝试所有子集或在删除后重复重新计算平均值的方法都会超时。 甚至$O(n \cdot m)$不可行，因为$m$可以达到$10^7$。 

一个关键的困难是这两种操作相互作用：删除元素会减少分母，而增加值会增加分子，但增量受到每个元素的限制并且全局受到限制。 

一些边缘案例暴露了常见的错误。 如果所有元素都相等，则说$n=3, a=[5,5,5]$，并且我们有很多操作，最好的策略是保留所有元素并分配增量，因为删除会减少分母而不提高比率。 天真的贪婪删除可能会错误地丢弃元素并人为地夸大平均值。 

另一种边缘情况是当一个元素与其他元素相比非常大时。 例如，$a=[1,1,1000]$。 最佳解决方案可能只保留最大的元素并对其进行增量投资。 假设我们必须保留大多数元素的策略在这里将会失败。 

当运营预算很大但每个元素都有上限时，就会出现最后一个微妙的情况$k$是有限制性的。 即使$m$很大，我们无法将所有增量转储到单个元素中； 我们必须将它们分配到选定的元素中，或者接受删除元素会改变我们可以投资的金额。 

## 方法

 蛮力视图会尝试超级英雄的每个可能的子集，然后模拟分布最多$m$跨元素递增，尊重每个元素的上限$k$。 对于每个子集，我们将对元素进行排序，并贪婪地将增量应用于最大收益。 即使忽略分布复杂性，仅枚举子集也是如此$O(2^n)$，这是不可能的$n=10^5$。 即使在排序后限制为前缀子集，仍然需要模拟最多$m$操作，速度太慢。 

关键的观察是我们可以分开决策：首先，假设我们固定大小的一个子集$x$。 在该子集中，我们总是希望首先将增量应用于最大的元素，因为每个增量对总和的贡献相等，但在应用于已经很大的值时，可以最大程度地提高平均值。 由于每个元素只能增加到$k$次，固定子集中可用增量的总数受下式限制：$x \cdot k$。 然而，我们也受到限制$m$，所以总可用增量是$\min(m, xk)$。 

现在问题变成：选择子集大小$x$, 取最好的$x$元素，并分布到$\min(m, xk)$其中增量。 由于增量总是指向子集中的最大元素，因此固定大小的最佳子集$x$简单来说就是$x$最大初始值。 

这减少了对数组进行排序并检查所有后缀（或前缀，取决于约定）、维护前缀总和并模拟可以应用多少增量的问题。 对于每个候选子集大小，我们有效地计算结果平均值。 

最终的优化是从最大元素向下考虑子集，因为删除小元素只能在最优增量分配后提高或保持平均值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n \cdot m)$|$O(n)$| 太慢了|
 | 最佳 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 对数组进行非降序排序。 这确保了当我们考虑保留子集时，最佳候选始终是最大的元素。 
2. 预先计算排序数组的前缀和，以便我们可以快速计算代表所选子集的任何后缀的和。 
3. 迭代可能的子集大小$x$从 1 到$n$，其中子集由$x$最大的元素。 
4. 对于每个子集大小$x$，计算我们可以应用多少总增量：这是$\min(m, x \cdot k)$。 这表示在子集级别组合的全局限制和每个元素限制。 
5. 通过始终增加最受益的元素来最佳地分配这些增量，这在固定排序子集中意味着最大的元素首先接收增量。 由于所有增量都会对总和加+1，因此分配不影响总和，只影响可行性，因此总增加值正是增量的数量。 
6. 计算子集大小的总功率$x$作为所选元素加上总增量的总和。 
7. 计算平均值为总功率除以$x$，并跟踪所有最大值$x$。 

### 为什么它有效

 在任何固定子集中，增量总是为总和贡献+1，无论哪个元素接收它们。 唯一的限制是每个元素上限的可行性$k$，这将总增量限制为最多$xk$。 由于删除元素只会减少分母，而不会增加每个元素的可用增量容量，因此最佳解决方案必须对应于某个子集大小$x$，并且在该子集中，所有增量分配在总贡献方面都是可以互换的。 这将问题简化为在排序的前缀选择上最大化简单的一维函数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort()
    
    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + a[i]
    
    ans = 0.0
    
    for x in range(1, n + 1):
        base_sum = prefix[n] - prefix[n - x]
        increments = min(m, x * k)
        total = base_sum + increments
        avg = total / x
        if avg > ans:
            ans = avg
    
    print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```该解决方案首先对数组进行排序，以便大小的任何最佳子集$x$可以假设由$x$最大的元素。 前缀和数组允许恒定时间检索任何此类子集和。 

对于每个子集大小，我们计算可以应用多少增量。 表达式`x * k`强制每个元素的上限，同时`m`强制执行全球上限。 这两者中的最小值决定了可用的增量。 

每个增量都会使总和恰好增加 1，因此我们直接将增量数添加到子集和中。 计算并比较所有子集大小的平均值。 

一个微妙的点是我们从不模拟动态删除元素； 相反，我们将问题重新解释为选择子集大小并直接对其进行评估。 这避免了昂贵的状态转换。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k, m = map(int, input().split())
    a = list(map(int, input().split()))

 ## 边缘情况

 一种边缘情况是所有元素都相同。 该算法评估每个子集大小，发现保留更多元素会增加分母，而不会增加每个元素增益超出删除允许的范围。 计算出的最大值将正确地来自增量被充分利用的最大有效子集。 

另一个边缘情况是单元素数组。 该算法仅评估$x=1$，适用于$\min(m,k)$递增，并返回正确的膨胀值，而不考虑任何子集。 

第三种边缘情况是当$m$非常小。 该算法正确地限制了全局增量，因此即使是大型子集也不会过度分配增量，从而防止高估平均值。
