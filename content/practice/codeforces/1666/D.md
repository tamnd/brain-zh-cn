 ## 解决方案
 ## 问题理解

 我们为每个测试用例提供两个字符串，一个初始单词和一个目标单词。 我们重复执行一个操作，允许我们选择一个字符并从当前单词中删除它最左边出现的位置。 这个过程可以重复任意多次，问题是我们是否可以将初始单词准确地转换为目标单词。 

一个关键细节是删除受到出现顺序的限制：当我们删除一个字符时，我们总是删除其最早出现的剩余出现，而不是任意出现的一个。 这意味着我们不能自由地重新排列字符； 我们只能以受控的方式从左到右“剥离”不需要的字母。 

每个字符串的长度最多为30，测试用例最多为10,000个。 这意味着即使是$O(n^2)$每个测试用例的方法是可以接受的，但是任何涉及对操作的删除或排列进行组合搜索的操作都会太慢或不必要。 

一个常见的失败案例是由于忽略“最左边出现”规则而引起的。 例如，如果初始字符串是`AAB`我们想要`BA`，一个天真的想法可能是我们可以删除一个`A`并隐式重新排列，但这种结构迫使我们仔细跟踪位置。 另一个微妙的失败是假设只要`t`存在于`s`，答案是肯定的。 这在排序约束上失败，例如`s = "ABAC"`和`t = "AAC"`其中相对位置使得在强制删除后无法保留所需的字母。 

核心困难在于，删除发生在全局序列中，并影响字符的未来可用性，因此我们必须推理是否存在一个删除序列能够准确地保留所需的子序列结构。 

## 方法

 暴力方法会尝试模拟所有可能的删除操作序列。 在每一步中，我们都可以选择仍然存在的任何字符并删除其第一次出现。 由于每个操作都会将字符串长度减少一，因此可能的序列数量随着字符串长度呈指数增长。 即使长度为 30，也会很快变得天文数字般大，使得这种方法不可行。 

关键的观察是我们实际上不需要模拟所有删除顺序。 相反，我们可以逆向思考：我们试图确定我们是否能够最终得到`t`通过有选择地删除字符`s`同时保留最左边删除规则施加的相对顺序约束。 

关键的见解是，如果一个角色`t`出现时，我们必须确保它可以与中的出现匹配`s`在删除所有早期字符后仍然存在。 由于删除总是删除第一个可用的出现，一旦我们传递一个字符`s`，我们永远不能“回去”将其用于以后的位置`t`。 这表明贪婪的从左到右的构造`t`里面`s`。 

我们尝试匹配`t`作为一个子序列`s`，但有一个更强的约束：我们必须确保每当我们消费一个角色时`s`，我们不会因为强制删除较早的不匹配项而使未来所需的匹配项无效。 形式化这一点的正确方法是模拟扫描`s`并贪婪地匹配字符`t`按顺序排列，还要确保未使用的字符`s`不要阻止未来的比赛。 

这简化为经典的子序列检查：如果我们能找到`t`作为一个子序列`s`，然后我们可以按照与最左边的删除一致的方式删除其他所有内容。 如果我们不能，那么一些必需的排序冲突会阻止`t`。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 从两个指针开始，一个在`s`和一上`t`，两者最初都在开始时。 指针在`s`代表我们在原始单词中扫描了多远，而指针在`t`跟踪我们成功匹配的目标字符数。 
2. 移动通过`s`从左到右。 在每个字符处`s`,检查是否与当前字符匹配`t`。 如果是，则将指针向前推进`t`一个。 这代表承诺使用此事件作为最终单词的一部分。 
3. 继续扫描直至结束`s`。 该过程自然会强制执行以下字符`t`按从左到右的顺序进行`s`，这符合我们不能通过删除来重新排序字符的约束。 
4. 扫描完所有内容后`s`，检查指针是否在`t`已经结束了`t`。 如果有，则每个字符`t`里面顺序匹配成功`s`，因此变换是可能的。 否则的话，那是不可能的。 

### 为什么它有效

 关键的不变量是在扫描期间的任何点`s`，前缀`t`到目前为止匹配的是在任何有效的删除序列下可以保留的最早可能的前缀。 因为删除总是删除所选字符的第一次出现，所以跳过的任何字符`s`如果不违反移除顺序，以后就不能使用。 因此，贪婪匹配确保我们永远不会错过可行的嵌入`t`，并且未能匹配意味着删除的重新排列无法恢复丢失的结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    out = []
    for _ in range(n):
        s, t = input().split()
        j = 0
        m = len(t)

        for ch in s:
            if j < m and ch == t[j]:
                j += 1

        out.append("YES" if j == m else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现直接对算法中描述的贪婪匹配进行编码。 指针`j`跟踪进度通过`t`，并且仅当在中找到匹配字符时才前进`s`。 条件`j < m`防止越界访问一次`t`提前完全匹配。 

一个微妙的点是我们从不显式模拟删除。 这是有意为之的：贪婪子序列检查隐式地对所有有效删除序列进行建模，因为匹配中未使用的任何字符都被假定在某个时刻是可删除的，而不会影响已匹配的结构。

 ## 边缘情况

 一种边缘情况是当`t`与`s`。 用于输入`s = "SOLUTION", t = "SOLUTION"`, 指针`j`每场角色比赛都会取得进展，并在最后准确结束。 该算法立即输出 YES，与不需要删除的事实相匹配。 

另一种情况是当`t`是一个子序列，但需要小心地跳过重复的字符，例如`s = "AABAAC", t = "AAC"`。 扫描结果与第一个匹配`A`, 跳过额外的`A`, 匹配`A`， 然后`C`，并成功。 这表明该算法自然地处理重复的字符，而无需显式簿记。 

一个看似失败但实际上有效的场景是`s`有额外的字符交错，例如`s = "XAYBZC", t = "ABC"`。 指针跳过不相关的字符，仍然匹配所有需要的字符，确认删除可以删除任意非必要字符而不影响可行性。
