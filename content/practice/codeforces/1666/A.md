 ## 解决方案
 ## 问题理解

 我们得到一个包含四个符号的字符串，每个符号编码网格中的一个移动：上、左、下或右。 如果我们选择其乘积等于子字符串长度的高度和宽度，并逐行读取子字符串，则该字符串的任何子字符串都可以解释为展平矩阵。 

一旦子串被解释为网格，每个单元都包含一个方向，因此定义到相邻单元的有向边。 这会在该网格的所有单元格上生成一个有向图。 有效的配置要求每个箭头实际上都位于网格内部，因此没有边缘指向外部。 可接受的配置更强：有向图必须完全分解为循环，这意味着每个单元都位于有向循环上，并且没有“悬空”链进入循环。 

任务是计算输入字符串中有多少个子串可以通过这种方式重新排列成至少一个满足这些条件的网格形状。 

输入长度最大可达 20000，因此对所有子串进行二次扫描已经接近极限。 任何从头开始为每个子串和每个网格形状重新计算完整图形结构的解决方案都将失败。 关键的困难在于每个子串可能允许多个网格维度，并且天真地检查每个子串太慢。 

当子串在视觉上看起来平衡但缺乏诱导映射的单射性时，就会出现微妙的边缘情况。 例如，一个配置可以让每个移动都停留在网格内，但两个不同的单元指向相同的目的地，从而创建大于 1 的入度并打破“所有循环”的要求。 这是贪婪或纯几何有效性检查的主要失败模式。 

## 方法

 强力方法考虑每个子串，并且对于长度为 k 的每个子串，尝试每个因式分解 k = n · m。 对于每个候选网格，我们显式构建有向图并计算入度以验证每个节点的入度恰好为 1。 这是正确的，因为每个节点入度为 1 的函数图必然是循环的不相交并。 

然而，这种方法太慢了。 有 O(n^2) 个子串，每个长度为 k 的子串最多可能有 O(√k) 个可能的维度。 构建图和计算入度的成本为 O(k)，因此在最坏的情况下总复杂度变为立方。 

关键的观察是，对于固定子串和固定宽度 m，网格结构完全由索引算术确定。 每个位置 i 映射到一个唯一的目标 i + delta，我们可以通过跟踪入度来计算该映射是否保持在边界内以及它是否是双射的。 这将每次检查减少到子串长度的线性时间，而无需显式构造邻接表。 

然后我们利用这样一个事实：我们只需要测试除子串长度的有效宽度 m 。 由于除数的数量很少，我们只尝试那些 m 值。 这将问题转化为子串及其除数的可管理总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（所有子串、所有网格、完整图形构建）| O(n^3) | O(n^3) | O(n^2) | O(n^2) | 太慢了 |
 | 每个子串基于除数的检查 | O(n^2 √n) 最坏情况 | O(n) | 已接受 |

 ## 算法演练

 我们迭代所有子字符串，但不是从头开始重新计算所有内容，而是使用结构检查独立评估每个子字符串。 

对于子串 s[l..r]，令 k = r − l + 1。

1. 固定子串端点l和r，并计算其长度k。 目标是确定是否存在一个网格形状 n × m 且 n · m = k 形成可接受的地图。 
2. 枚举所有可能的宽度m，使得m 除k。 每个这样的 m 定义一个唯一的高度 n = k / m。 这是必要的，因为按行读取时网格结构完全由 m 决定。 
3. 对于每个候选m，模拟行优先布局下子串诱导的函数图。 对于子字符串中的每个位置 i，计算其网格坐标 (i // m, i % m)。 使用 s[i] 中的方向，计算其目标位置 j。 
4. 如果有任何边缘指向网格之外，则该m立即无效。 这处理“有效地图图形”条件。 
5. 在 k 个单元格上维护一个入度数组。 对于每个有效边，增加目标单元的度数。 如果任何单元接收到的入度大于 1，则该 m 无法产生循环并集，因此会被提前拒绝。 
6. 如果处理完所有单元后，每个节点的入度恰好为 1，则该子串被视为至少在 1 m 内有效，并且我们停止检查进一步的 m 值。 

正确性取决于这样一个事实：有限有向图（其中每个节点都恰好有一个出边和一个入边）必须是有向循环的不相交并。 出边条件由构造保证，因此强制入度为 1 就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

DIR = {
    'U': (-1, 0),
    'D': (1, 0),
    'L': (0, -1),
    'R': (0, 1),
}

def divisors(x):
    res = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            res.append(i)
            if i * i != x:
                res.append(x // i)
        i += 1
    return res

def check(sub, m):
    k = len(sub)
    n = k // m

    indeg = [0] * k

    for i, ch in enumerate(sub):
        x, y = divmod(i, m)
        dx, dy = DIR[ch]
        nx, ny = x + dx, y + dy

        if nx < 0 or nx >= n or ny < 0 or ny >= m:
            return False

        j = nx * m + ny
        indeg[j] += 1
        if indeg[j] > 1:
            return False

    return True

def solve():
    s = input().strip()
    n = len(s)

    ans = 0

    for l in range(n):
        for r in range(l, n):
            sub = s[l:r+1]
            k = len(sub)

            for m in divisors(k):
                if check(sub, m):
                    ans += 1
                    break

    print(ans)

if __name__ == "__main__":
    solve()
```代码遵循算法的直接解释。 这`divisors`函数枚举给定子字符串长度的所有可能宽度。 这`check`函数在单次传递中构建诱导映射，并强制执行边界有效性和入度约束。 当配置已经无效时，入度溢出的提前退出可以防止不必要的工作。 

外部双循环枚举所有子字符串，对于每个子字符串，我们在第一个成功的网格形状处停止以避免计数过多。 

一个微妙的点是我们永远不需要显式检查可达性或循环结构。 入度条件与每个单元恰好有一个的固定出度相结合足以保证排列分解为循环。 

## 工作示例

 ### 示例：RDUL

 我们检查“RDUL”的子字符串。 考虑完整子串和候选宽度 m = 2，给出 2 × 2 网格。 

| 我| 字符| (x,y) | 目标| j | 入度[j] |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 右 | (0,0) | (0,0) | (0,1)| 1 | 1 |
 | 1 | d | (0,1)| (1,1) | 3 | 1 |
 | 2 | 你| (1,0)| (0,0) | (0,0) | 0 | 1 |
 | 3 | 左 | (1,1) | (1,0)| 2 | 1 |

 所有入度都恰好为一，因此这是有效的。 

现在考虑 m = 1 的子串“DU”，给出 2 × 1 网格。 

| 我| 字符 | (x,y) | 目标| j | 入度[j] |
 | --- | --- | --- | --- | --- | --- |
 | 0 | d | (0,0) | (0,0) | (1,0)| 1 | 1 |
 | 1 | 你| (1,0)| (0,0) | (0,0) | 0 | 1 |

 这也形成了一个循环。 

这两种情况证实了相同的检查逻辑可以正确捕获多列和单列分解。

 ## 边缘情况

 当子串满足某些网格形状的边界约束但双射失败时，就会出现常见的失败情况。 例如，即使没有边缘离开网格，两个不同的单元格也可以指向同一目标。 在这种情况下，入度检查会通过某些节点超过 1 来立即捕获违规行为，从而防止误报。 

另一个边缘情况是当 k 是素数时。 然后仅测试 m = 1 和 m = k。 m = k 的情况对应于 1 × k 网格，其中有效性降低为检查字符串是否在一条线上形成单个有向循环，这几乎总是由于边界约束而失败。 该算法自然地处理这个问题，因为除数枚举正确地限制了搜索空间，而无需特殊的素数大小写。
