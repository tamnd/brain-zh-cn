 ## 解决方案
 ## 问题理解

 该问题为我们提供了表示堆栈上操作的整数序列。 每个整数都可以被视为将一个新元素推入堆栈或执行“奇特”操作，以受问题规则控制的方式从顶部删除一些元素。 目标是为整个序列确定满足这些规则的特定操作计数或总和。 

更具体地说，堆栈是动态的，并且可能具有连续相同值的块。 操作序列可能很长，最多可达$n = 2 \cdot 10^5$，这意味着任何算法都比$O(n \log n)$可能太慢了。 逐个元素模拟每个操作的简单方法是$O(n^2)$在最坏的情况下，因此不可行。 

边缘情况包括严格递增、严格递减或完全一致的序列。 例如，像这样的序列`[1,1,1,1]`如果算法尝试错误地合并连续元素，可能会触发堆栈的重复崩溃。 另一个边缘情况是交替序列，例如`[1,2,1,2,1,2]`，天真的合并假设可能会失败，因为合并仅在非常特定的条件下发生。 

## 方法

 蛮力方法准确地模拟了堆栈。 对于序列中的每个元素，将其推入堆栈并检查是否可以根据规则发生“奇特”折叠（例如，顶部$x$元素相同）。 如果发生崩溃，您可以删除该块并更新一些计数。 虽然这在概念上是简单且正确的，但每次删除都可能会触及$O(n)$元素在序列上累积，导致$O(n^2)$最坏情况序列的行为，例如`[1,1,1,1,...,1]`。 

关键的见解是我们不需要记住每个单独的元素。 相反，我们可以存储连续相同元素的块及其计数。 每次推送要么增加顶部块的计数（如果匹配），要么创建一个新块。 当计数达到元素的值（“奇特”条件）时，块就会崩溃。 这将问题从每个元素模拟减少到每个块模拟，保证$O(n)$自每个元素最多参与一次崩溃以来的时间。 

从暴力破解到基于块的模拟的转变是通过观察堆栈在具有相同值的块内一致表现来实现的，并且一旦块形成，我们就不需要查看块的内部，除非它完全崩溃。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了|
 | 基于块的模拟| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 初始化一个空堆栈。 堆栈中的每个条目都是一个元组`(value, count)`表示连续相同值的块。 初始化一个变量`answer`来积累结果。 
2. 迭代整数序列。 对于每个整数`x`，检查堆栈的顶部块。 
3. 如果堆栈为空或者顶部块的值与`x`， 推`(x, 1)`到堆栈上。 这将开始一个新的块。 
4. 如果顶部块的值等于`x`，增加其计数。 
5.递增后，检查顶部块的计数是否等于`x`。 如果是，则该块满足“花式崩溃”条件。 从堆栈中弹出块并递增`answer`1.
 6. 继续迭代，直到处理完整个序列。 

工作原理：不变的是堆栈始终存储连续相同值的块，并且计数正确地表示块大小。 因为只有当块大小等于其值时才会发生崩溃，所以任何块都不会过早崩溃，并且每次崩溃都会被精确计数一次。 每个元素最多被压入和弹出一次，保证线性时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    stack = []
    answer = 0
    
    for x in arr:
        if stack and stack[-1][0] == x:
            val, cnt = stack.pop()
            cnt += 1
            if cnt == x:
                answer += 1
            else:
                stack.append((val, cnt))
        else:
            if x == 1:
                answer += 1
            else:
                stack.append((x, 1))
    
    print(answer)

if __name__ == "__main__":
    solve()
```该代码反映了基于块的方法。 每个堆栈条目`(value, count)`捕获均匀块。 支票`cnt == x`强制“花式崩溃”。 边缘情况如`x == 1`显式处理以避免创建不必要的块。 堆栈操作保证没有元素被访问超过两次。

 ## 边缘情况

 顺序`[1,1,1,1]`显示单元素块立即崩溃`x==1`。 每个元素都有助于`answer`单独地，因此算法正确地递增四次。 

交替序列`[1,2,1,2,1,2]`证明块不会过早崩溃。 堆栈包含不完整的块，直到它们满为止，确保不会错误计数。 每次崩溃恰好在顶部块计数等于该值时发生。 

序列如`[3,3,3,2,2,2]`确认多个崩溃可以连续发生，并且剩余的块保留在堆栈中以进行进一步的操作，这表明不变量始终保持不变。 

这篇社论的目的是让读者只需观察连续的相同元素只需要通过计数来跟踪，并且当计数与值匹配时就会发生崩溃，从而简单地重新推导堆栈与块解决方案。
