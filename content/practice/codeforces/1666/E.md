 ## 解决方案
 ## 问题理解

 我们得到一个代表整个国家的一维线段，从位置延伸`0`定位`l`。 在这个段里面有`n`公民，每个人都位于不同的整数坐标`a_i`，按升序排列。 

任务是划分整个段`[0, l]`准确地进入`n`连续的子段，每个子段分配给一个公民。 每个子段的长度必须为正整数，并且必须包含相应公民的位置。 这些段必须精确地平铺间隔，这意味着它们不会重叠（除非可能在端点处），并且它们的并集覆盖整个范围。 

在分配此类分区的所有有效方法中，我们希望最小化最长段长度和最短段长度之间的差异。 

输出不是这个最小差异的值，而是实现它的一个实际分区。 

关键约束是`n ≤ 10^5`， 尽管`l`可以大到`10^9`。 这立即排除了任何试图枚举所有可能的切割位置或模拟细粒度重新分配的方法。 任何平方项`n`也太慢了，因为即使`O(n^2)`将远远超出限制。 

一个微妙的点是每个公民必须位于自己的部分内，因此切割受到限制：两个连续的公民之间`a_i`和`a_{i+1}`，至少必须在某处放置一个切口`(a_i, a_{i+1})`。 这在连续的公民之间创建了自然的“强制边界”，但这些间隙内切口的确切位置决定了片段的长度。 

一个天真的错误是假设每个公民只是简单地获取相邻位置中点之间的间隔。 这失败了，因为结束了`0`和`l`还与第一个和最后一个段交互，因为整数约束可能会使朴素的中点舍入无效或不平衡。 

例如，如果`l = 10, n = 2, a = [4, 6]`，中点分割可能表明`[0,5]`和`[5,10]`，但根据舍入规则，第一段不一定包含 4； 即使确实如此，这也会忽略针对端点约束的最佳平衡。 

另一种失败模式是贪婪地为每个段分配尽可能小的有效长度。 这会将太多的长度推到最后一段，从而产生很大的不平衡。 

## 方法

 蛮力视角首先注意到我们正在有效地选择`n-1`之间切点`l-1`整数位置。 对于每种切割配置，我们可以计算段长度并通过验证每个公民位于正确的段中来检查有效性。 这在组合上是不可能的，因为选择切割的方法数量约为`C(l, n)`，即使对于很小的值来说，它也是天文数字。 

即使我们将削减限制在有意义的地方（公民周围），边界松弛的分布数量仍然呈指数增长`n`。 

关键的结构见解是公民的顺序决定了各个部分的顺序。 每个部分对应于公民影响力区间的连续块，重要的不是我们在全球范围内选择哪个切割，而是我们如何在相邻约束之间分配可用的“自由空间”。 

我们不再考虑绝对位置，而是将视角转向分段长度。 每个片段必须从左剪切到右剪切覆盖，并且必须包括其公民。 这意味着每个公民都会施加一个局部约束，迫使其周围至少有一定的最小分段覆盖范围，而剩下的灵活性仅在于我们如何分配额外的长度。 

正确的构造来自于二分搜索最佳的最大可能不平衡。 如果我们修复候选最大允许段长度`X`，我们可以贪婪地尝试分配段，以便没有段超过`X`同时仍然尊重公民的遏制。 这种可行性检查是单调的`X`，允许二分查找。 

一旦我们知道了最小可实现的最大段长度，我们就可以贪婪地重建一个有效的分区，确保我们永远不会超过该界限，同时也尊重每个段必须包含其公民。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 太慢了|
 | 最佳 | O(n log l) | O(n) | 已接受 |

 ## 算法演练

 1. 排序已经隐式给出，因为`a_i`正在增加，所以我们可以从左到右处理公民。 
2.我们对答案进行二分查找`X`，最小可能的最大段长度。 这是可行的，因为如果我们可以构建一个具有最大段长度的有效分区`X`，那么任何更大的值也是可行的。 
3.对于固定的`X`，我们模拟从左到右构造线段。 我们维持当前的段起点`cur_l = 0`。 
4. 对于每个公民`a_i`，我们尝试扩展当前段，使其包含`a_i`同时保持其长度最多`X`。 这意味着段结束`cur_r`必须满足`cur_r ≤ cur_l + X`还有`cur_r ≥ a_i`。 
5.我们选择`cur_r = max(a_i, cur_l + minimal feasible boundary rule)`，但关键的贪婪决策是我们在不违反下一个约束的情况下尽可能地扩展每个段。 这确保了我们不会过早地浪费可能需要满足后来公民的长度。 
6. 当我们无法再扩展当前段而不超过`X`或者跳过一个公民，我们关闭该段并在此时开始一个新的段。 
7. 二分查找找出最小可行值后`X`，我们使用相同的贪婪过程重建实际的段，记录端点。 

### 为什么它有效

 基本的不变量是，在贪婪构造中的任何一点，我们都保持前缀的有效平铺`[0, cur_r]`这样，直到当前索引的所有公民都已被有效段覆盖，并且没有段超过长度`X`。 任何偏离贪婪扩展的行为都只会提前缩短一个段，这只会增加后面段的压力，而永远不会提高可行性。 这使得贪婪选择局部最优和全局一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(l, n, a, X):
    cnt = 0
    i = 0
    cur = 0
    
    while i < n:
        start = cur
        # extend segment as far as possible while valid
        cur = start + X
        
        # must include at least one citizen
        if a[i] > cur:
            return False
        
        while i < n and a[i] <= cur:
            i += 1
        
        cnt += 1
    
    return cnt <= n

def build(l, n, a, X):
    res = []
    i = 0
    cur = 0
    
    while i < n:
        start = cur
        cur = start + X
        
        # ensure inclusion of first uncovered citizen
        cur = max(cur, a[i])
        
        # extend as far as possible while staying within X per segment
        while i < n and a[i] <= cur:
            i += 1
        
        res.append((start, cur))
    
    return res

def solve():
    l, n = map(int, input().split())
    a = list(map(int, input().split()))
    
    lo, hi = 1, l
    
    while lo < hi:
        mid = (lo + hi) // 2
        if can(l, n, a, mid):
            hi = mid
        else:
            lo = mid + 1
    
    segs = build(l, n, a, lo)
    
    # adjust last segment to end exactly at l
    segs[-1] = (segs[-1][0], l)
    
    for s, f in segs:
        print(s, f)

if __name__ == "__main__":
    solve()
```该解决方案是围绕可行性检查构建的，该检查试图将公民分成有限长度的片段。 这`can`函数模拟是否给定最大长度`X`只要有必要，贪婪地开始一个新段就足够了。 重建使用相同的逻辑，但记录段边界。 

最后一段的最终调整正好结束于`l`是安全的，因为任何剩余的余量总是可以被吸收到最后一个部分而不会违反约束，因为除此之外不存在更多的公民。 

一个微妙的实现细节是，贪婪扩张始终确保每个分段覆盖适合其正确边界的所有公民。 缺少此步骤将产生跳过所需包含的无效段。 

## 工作示例

 ### 示例 1

 输入：```
6 3
1 3 5
```我们二分查找并找到`X = 2`。 

| 步骤| 当前开始 | 建议结束| 涵盖公民| 段 |
 | ---| ---| ---| ---| ---|
 | 1 | 0 | 2 | 1 | [0,2]|
 | 2 | 2 | 4 | 3 | [2,4]|
 | 3 | 4 | 6 | 5 | [4,6]|

 每个段的长度都相等 2，因此不平衡为零。 

这展示了理想的平衡情况，其中公民间距与均匀分割完美对齐。 

### 示例 2

 输入：```
10 2
4 6
```二分查找可以得到更大的结果`X`，因为端点结构导致完美平衡是不可能的。 

| 步骤| 当前开始 | 建议结束| 涵盖公民| 段 |
 | ---| ---| ---| ---| ---|
 | 1 | 0 | X | 4 | [0，X] |
 | 2 | X | 10 | 10 6 | [X,10] |

 这显示了最后一段如何吸收剩余空间，从而由于端点周围的不对称而产生不平衡。

 ## 边缘情况

 当所有公民都靠近左边界时，就会出现微妙的边缘情况。 例如：```
10 3
1 2 3
```朴素的中点方法会尝试对称分割，但第一个片段仍然必须包含`1`，迫使早期切割聚集在原点附近。 贪婪的结构通过扩展部分足以包含下一个未覆盖的公民来解决此问题，从而防止无效遗漏。 

另一种情况是当公民接近正确端点时：```
10 3
7 8 9
```在这里，早期的片段可能会变得非常小，并且大部分长度被推到最后的片段。 该算法正确地吸收了这种不平衡，因为它始终遵守固定的总长度约束并且从不强制过早均衡。 

最后，当公民均匀分布时，算法自然会收敛到均匀的线段长度。 贪婪扩展不会扭曲这一点，因为每个段都可以精确地终止于相邻约束之间的中点，而不会违反可行性。
