 ## 解决方案
 ## 问题理解

 我们有一个二分结构，其中一侧由学生组成，另一侧由槽组成，称为平行结构。 每个学生都连接到这些槽位的某个子集，并且连接意味着该学生有资格被分配到该槽位。 

任务是在单个全局约束下选择尽可能多的学生：必须存在一个匹配，将每个选定的学生分配到他们所连接的不同插槽。 每个槽位最多可以使用一次，并且必须为每个被选中的学生分配恰好一个槽位。 

换句话说，我们不是要求匹配所有人，而是选择可以同时匹配而不会发生冲突的学生子集。 

输入大小通常允许边缘数量达到线性或接近线性比例。 这立即排除了任何从头开始重复计算许多候选子集匹配的方法。 对子集进行简单的指数搜索也是不可能的，因为子集的数量以 2^n 的形式增长，并且当 n 很大时，即使对所有子集进行二次探索也会超出限制。 

当学生争夺共享名额时，幼稚贪婪思维的微妙失败案例就会出现。 例如，假设学生 1 可以使用槽 {A, B}，学生 2 可以使用 {A}，学生 3 可以使用 {B}。 优先考虑学生 1 的贪婪作业可能会过早消耗插槽 A 或 B 并阻塞更大的可行子集。 正确答案取决于全局结构，而不是局部偏好。 

如果我们试图独立匹配每个学生而不协调作业，就会出现另一个问题。 即使每个学生都有一个可用的位置，他们的选择也可能会发生冲突，从而为整个子集产生不可行的作业。 

## 方法

 一种直接的方法是尝试所有学生子集并测试每个子集是否承认有效匹配。 对于大小为 k 的固定子集，我们可以运行二分匹配算法，例如 Kuhn 的 DFS 方法或最大流。 如果我们对每个子集都这样做，我们最终会进行最多 2^n 次匹配检查，每次至少花费 O(E)，即使 n 约为 20，这也会变得天文数字。 

更结构化的尝试是观察子集的可行性恰好是二分匹配条件。 我们可以尝试在整个图上构建最大匹配，而不是检查子集。 二分匹配的一个关键特性是它已经找到了左侧可以同时匹配的最大可能数量的顶点。 

关键的见解是，任何可以匹配的学生子集都对应于原始图中的匹配，相反，任何匹配都定义了匹配学生的子集。 因此，最大化子集的大小相当于最大化匹配的学生数量，这正是最大二分匹配的大小。 

这将问题从子集选择减少到单个最大匹配计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集+匹配| O(2^n·E) | O(2^n·E) | O(E) | 太慢了|
 | 最大二分匹配 | O(VE) 或 O(E√V) 取决于算法 | O(E) | 已接受 |

 ## 算法演练

 我们将问题简化为在二分图中找到最大匹配，其中学生位于左侧，平行线位于右侧。

1. 构建从学生到所有兼容平行线的邻接列表。 这对可能出现在任何有效解决方案中的所有可能的分配进行编码。 
2. 运行标准二分最大匹配算法，例如 Kuhn 的 DFS 增广路径方法。 这个想法是反复尝试匹配每个学生，如果他们的首选位置被占用，则尝试将当前的持有者重新分配到其他地方。 
3. 维护一个数组，记录当前与每个槽位匹配的学生。 当尝试匹配新学生时，我们要么找到一个空闲位置，要么沿着交替路径递归地移动现有作业。 
4. 每次我们成功匹配一个学生时，我们都会增加匹配的规模。 直接跟踪匹配学生的最终计数。 
5.处理完所有学生后，输出匹配的学生数量，代表可以同时分配的最大子集。 

这个过程起作用的原因是它逐步构建了最大的不相交作业集，并且每次增强都会严格增加匹配学生的数量，直到不可能进一步改进。 

### 为什么它有效

 在算法中的任何点，当前匹配都满足以下属性：相对于所探索的结构不存在增广路径。 根据二部匹配的经典定理，当且仅当不存在增广路径时，匹配才是最大的。 由于该算法一直持续到无法从任何不匹配的学生中找到增广路径为止，因此所得到的匹配必须是全局最优的。 每个匹配的学生都对应于可行子集的一个元素，而每个可行子集都对应于某种匹配，因此最大化一个元素会最大化另一个元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    
    for i in range(n):
        row = list(map(int, input().split()))
        # assume format: first number is k, then k neighbors (1-indexed parallels)
        k = row[0]
        for v in row[1:]:
            g[i].append(v - 1)
    
    match_to_student = [-1] * m

    def dfs(u, vis):
        for v in g[u]:
            if vis[v]:
                continue
            vis[v] = True
            if match_to_student[v] == -1 or dfs(match_to_student[v], vis):
                match_to_student[v] = u
                return True
        return False

    ans = 0
    for i in range(n):
        vis = [False] * m
        if dfs(i, vis):
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现遵循经典的库恩匹配结构。 邻接列表为每个学生存储可以分配给他们的所有可能的平行项。 

这`match_to_student`数组跟踪当前哪个学生占据每个平行线。 值为`-1`表示空闲槽位。 

DFS 尝试将学生分配到任何可用的插槽，如果该插槽已被占用，它会递归地尝试将现有学生重新分配到其他地方。 访问的数组可防止在单次增强尝试中发生循环。 

每个成功的 DFS 调用都会增加匹配大小，我们会累积此计数作为答案。 

一个微妙的点是为每个开始的学生重置访问的数组。 这确保了每个增强搜索都是独立的，这是库恩算法的正确性所必需的。 

## 工作示例

 ### 示例 1

 考虑 3 个学生和 2 个平行对象。 

学生 1：{1, 2}

 学生 2：{1}

 学生 3：{2}

 我们跟踪匹配的构造。 

| 步骤| 学生| 已访问老虎机 | 比赛状态| 行动|
 | ---| ---| ---| ---| ---|
 | 1 | 1 | {1,2} | 1→插槽1 | 直接赋值 |
 | 2 | 2 | {1} | 1→插槽1 | slot1 已被占用，无备用路径 |
 | 3 | 3 | {2} | 1→插槽1，3→插槽2 | 直接赋值 |

 处理后，可以同时匹配两个学生（例如学生 1 和 3 或学生 2 和 3，具体取决于顺序）。 

这表明该算法不会贪婪地锁定单个分配模式，而是通过增广路径探索重新路由。 

### 示例 2

 学生 1：{1}

 学生 2：{1}

 学生 3：{1}

 仅存在一个插槽。 

| 步骤| 学生| 访问过 | 比赛状态| 行动|
 | ---| ---| ---| ---| ---|
 | 1 | 1 | {1} | 1→1 | 已分配 |
 | 2 | 2 | {1} | 1→1 | 无法取代 1 |
 | 3 | 3 | {1} | 1→1 | 无法取代 1 |

 仅匹配一名学生，这是最佳选择，因为所有人都竞争一个位置。

 ## 边缘情况

 一个重要的边缘情况是每个学生都连接到完全相同的单个插槽。 在这种情况下，算法将匹配第一个学生，而让所有其他学生不匹配。 由于不存在增广路径，后续学生的 DFS 尝试将立即失败，从而正确生成答案 1。 

另一种情况是，当图表形成链状依赖关系时，只有移动较早的学生才能匹配较晚的学生。 增广路径搜索自然地处理了这个问题。 例如，如果学生 1 使用槽 A，学生 2 可以使用 A 或 B，而学生 3 只能使用 B，则在处理学生 3 时，算法可能会在可能的情况下将学生 2 从 B 重新路由到 A，从而为学生 3 释放 B。这表明正确性并不取决于输入顺序，而是取决于匹配图中是否存在交替路径。
