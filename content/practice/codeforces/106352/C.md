 ## 解决方案
 ## 问题理解

 我们得到了放在一排保险箱上的一系列数字。 每个保险箱都带有一个整数标签，并且该标签仅通过其素因数才重要。 对于任何查询段$[l, r]$，我们需要构建一个整数$d \ge 2$这样它就可以打开该段中的每个保险箱。 保险箱被打开$d$恰好在什么时候$d$与保险箱的号码没有共同的素因数，因此对于每个$a_i$在我们需要的部分$\gcd(d, a_i) = 1$。 

任务不是构建任何有效的$d$，而是为每个查询找到尽可能小的一个。 

这些约束促使我们寻求一种解决方案，在该解决方案中，我们无法从头开始重新计算每个查询的任何内容。 高达$2 \cdot 10^5$对于元素和查询，每个查询的因式分解或对数组的扫描将立即超出线性甚至接近线性的预算。 在最坏的情况下，诸如重新计算每个查询的素数集或一一测试候选者之类的任何操作都会太慢，因为数组和查询数量都足够大，足以强制粗略地执行$10^{10}$在简单的设置中进行缩放操作。 

当该段包含许多小素数但错过了一些稍大的素数时，就会出现一种微妙的边缘情况。 例如，如果一个段包含可被 2、3、5、7 整除的数字，但不能被 11 整除，则正确答案为 11，即使存在所有较小的合数（如 9 或 25）。 按顺序尝试整数并针对段检查 gcd 的天真尝试将会失败，因为针对整个段检查每个候选者的成本太高。 

另一个陷阱是假设我们需要避免所有素数出现在数组中的任何位置。 这是不正确的，因为答案仅取决于细分市场。 素数可能会出现在全局范围内，但不会出现在特定的查询范围内，然后它就成为该查询的最佳答案。 

## 方法

 直接方法将独立处理每个查询。 对于一个段$[l, r]$，我们可以收集所有的素因数$a_i$在该段中，然后测试从 2 开始向上的整数，直到找到一个素因子避开该集合的整数。 这是正确的，但它太慢了，因为每个查询可能会触及$O(n)$值，并且每个值都需要因式分解。 即使进行快速因式分解，也要重复此过程$2 \cdot 10^5$查询是不可行的。 

关键的结构观察是，当且仅当一个数的所有质因数都避免了段中存在的质因数的并集时，该数才是有效的。 这将问题简化为跟踪段中哪些素数是“活跃的”。 我们不需要推理任意整数，而只需要推理素数，因为任何复合候选值在值上都比其最小素数因子更差。 

因此，一个线段的答案就是不能整除该线段中任何数字的最小素数。 

这将问题转化为动态范围问题：维护当前段中出现的一组素数，并反复询问其中不存在的最小素数。 这是一个经典的“通过全局最小查询维持滑动窗口上的频率”设置，它适合 Mo 的算法与素数上的线段树的结合。 

我们预先计算所有素数直到数组中的最大值，按排序顺序为每个素数分配一个索引，并维护一个频率计数器来指示活动段中当前是否存在素数。 素数线段树为素数的每个区间存储频率为零的最小素数。 移动 Mo 窗口时更新切换素数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(q \cdot n \cdot \sqrt{A})$|$O(1)$额外 | 太慢了|
 | Mo+素线段树|$O((n+q)\sqrt{n} \log P)$|$O(n + P)$| 已接受 |

 这里$P$是最大素数个数$a_i$。 

## 算法演练

 我们依赖两种结构一起工作：将每个数字分解为不同的素数因子，以及跟踪活动查询段中当前存在哪些素数的动态数据结构。 

### 1. 预先计算最小质因数

 我们首先筛选所有数字$10^7$获得每个整数的最小质因数。 这使我们能够考虑任何$a_i$在线性时间内快速超过其不同素数的数量。 

### 2. 提取每个位置的素数集

 对于每个索引$i$，我们考虑因素$a_i$使用 SPF 数组并仅存储不同的素因数。 重复的素数是无关紧要的，因为段中的存在是二元的。 

### 3. 构建全局素数列表

 我们枚举直到最大值的所有素数，并按升序为它们分配索引。 这种排序至关重要，因为答案取决于最小的可用素数。 

### 4. 初始化素数上的线段树

 每片叶子对应一个素数。 如果活动段当前不存在素数，则其叶子存储其值； 否则它存储无穷大。 内部节点存储其子节点的最小值，因此根总是给出最小的缺失素数。 

### 5. 使用 Mo 的排序处理查询

 我们按 Mo 顺序对查询进行排序并维护滑动窗口$[L, R]$。 当我们移动边界时，我们会添加或删除位置，从而相应地更新主频率。 

### 6.更新频率结构

 当添加一个位置时，每个质因数$a_i$增加其计数。 如果素数从 0 转变为 1，它将变为活动状态并从线段树中的可用性中删除。 删除后，如果其计数返回到 0，则它再次可用。 

### 7. 回答每个问题

 调整窗口以匹配查询后，答案就是存储在线段树根中的最小值。 

### 为什么它有效

 在任何时刻，线段树都准确地表示当前范围内未出现的素数集合。 任何有效整数都必须避免段中出现所有素数，因此它必须仅由标记为不存在的素数组成。 在所有此类整数中，最小的始终是最小的可用素数，因为任何合数都大于其素数因子中的至少一个。 因此线段树的根直接编码最优答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXV = 10**7

spf = list(range(MAXV + 1))
for i in range(2, int(MAXV ** 0.5) + 1):
    if spf[i] == i:
        step = i
        start = i * i
        for j in range(start, MAXV + 1, step):
            if spf[j] == j:
                spf[j] = i

def factorize(x):
    res = []
    while x > 1:
        p = spf[x]
        res.append(p)
        while x % p == 0:
            x //= p
    return res

class SegTree:
    def __init__(self, vals):
        self.n = len(vals)
        self.INF = 10**18
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.data = [self.INF] * (2 * self.size)
        for i, v in enumerate(vals):
            self.data[self.size + i] = v
        for i in range(self.size - 1, 0, -1):
            self.data[i] = min(self.data[2 * i], self.data[2 * i + 1])

    def update(self, idx, val):
        i = self.size + idx
        self.data[i] = val
        i //= 2
        while i:
            self.data[i] = min(self.data[2 * i], self.data[2 * i + 1])
            i //= 2

    def query_min(self):
        return self.data[1]

def main():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    primes = set()
    fac = []
    for x in a:
        ps = factorize(x)
        fac.append(ps)
        primes.update(ps)

    primes = sorted(primes)
    idx = {p: i for i, p in enumerate(primes)}

    cnt = [0] * len(primes)
    base = primes[:]
    seg = SegTree(base)

    def add(i):
        for p in fac[i]:
            j = idx[p]
            cnt[j] += 1
            if cnt[j] == 1:
                seg.update(j, 10**18)

    def remove(i):
        for p in fac[i]:
            j = idx[p]
            cnt[j] -= 1
            if cnt[j] == 0:
                seg.update(j, primes[j])

    BLOCK = int(n ** 0.5)
    queries = []
    for i in range(q):
        l, r = map(int, input().split())
        queries.append((l - 1, r - 1, i))

    queries.sort(key=lambda x: (x[0] // BLOCK, x[1]))

    ans = [0] * q
    curL, curR = 0, -1

    for l, r, i in queries:
        while curL > l:
            curL -= 1
            add(curL)
        while curR < r:
            curR += 1
            add(curR)
        while curL < l:
            remove(curL)
            curL += 1
        while curR > r:
            remove(curR)
            curR -= 1
        ans[i] = seg.query_min()

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    main()
```该实现首先构建最小的质因数以实现快速分解。 每个数组元素都被简化为其一组不同的素因数，这对于互质约束来说是最重要的。 Mo 排序确保每个元素添加或删除的次数有限，而线段树则在当前不可用的素数上保持全局最小值。 

一个微妙的细节是，我们在线段树中为活动素数存储“无限”，因此它们永远不会影响最小值，而非活动素数则存储其实际值。 这种反转允许根始终代表最小的有效候选者。

 ## 边缘情况

 一个关键的边缘情况是每个小素数都出现在段中的某个位置。 例如，如果线段包含涵盖素数 2、3、5 和 7 的数字，则答案必须跳转到 11。该算法会处理此问题，因为所有这些素数都被标记为活动状态，并且线段树根自然会返回下一个可用素数。 

另一种情况是当该段是单个元素（例如 12）时，它贡献素数 {2, 3}。 最小的有效整数是 5，而不是 4 或 6，因为两者都包含至少一个禁止素数。 该结构正确返回 5，因为 2 和 3 被标记为不可用。 

最后，当素数在移动查询窗口后消失时，它立即再次有效。 这是通过减少 Mo 算法中的计数器并恢复其在线段树中的值来处理的，从而确保转换期间的正确性。
