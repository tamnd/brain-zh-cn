 ## 解决方案
 ## 问题理解

 我们得到了一系列数字和两名玩家，他们不断地缩小它，直到只有一个值保留在前面的位置。 每次移动都会删除一个元素，但在删除之前，会更新所选相邻对的左侧元素。 一个玩家总是试图使这个不断变化的值尽可能大，而另一个玩家总是试图尽可能地抑制它。 

关键的观察是，只有最终成为第一个元素的值才重要。 其他一切都只是在数组崩溃时通过一系列最大和最小交互影响该值的工具。 

约束允许最多$10^5$总体而言，每个测试的元素都不同，因此任何模拟所有游戏状态或考虑每个可能的合并序列的方法都是不可能的。 该过程每次移动都会将长度减少一，因此有$O(n)$每次测试都会移动，但每个移动都取决于策略选择。 所有选择的朴素极小极大将会呈指数级分支。 

当所有值都相等时，会出现微妙的边缘情况。 那样的话，每一次操作都是中立的，答案一定保持不变。 另一个极端情况是当最大元素不在开始附近时，因为天真的直觉可能表明只有局部值很重要，但实际上可以通过重复合并将值拉向索引 1。 

## 方法

 暴力模拟将尝试对两个玩家的每一个可能的动作进行建模，并在每一步中对所有有效索引进行分支。 由于每次移动都会将序列长度减少一，因此有$n-1$决策，并且每个决策都可以在$O(n)$方式，导致指数数量的状态。 即使修剪也无济于事，因为每次移动的效果都会以非局部方式改变未来的最佳选择。 

关键的见解是，游戏不会以复杂的方式保留顺序，只有值对最终位置的相对影响才重要。 每个操作要么向左传播最大值，要么向左传播最小值。 这意味着最终值不是由完整的策略树决定，而是由数组的单个结构属性决定：哪些元素可以在交替的最大-最小收缩中幸存下来，同时保持影响力。 

事实证明，最优玩法会崩溃为贪婪的表征：第一个元素最终将成为在交替支配约束下可达到的最佳值，这可以直接计算而无需模拟游戏。 

这种减少来自于将该过程解释为一系列强制的成对减少。 我们不考虑移动方式，而是跟踪位置 1 处的值在交替最大/最小控制下与其右侧的每个元素竞争时如何演变。 这完全消除了游戏模拟的需要。

 ## 算法演练

 最佳解决方案基于处理交替控制下第一个元素如何受到其余元素的影响。 

1. 从最初的第一个元素开始作为当前候选答案。 这是我们直接跟踪的唯一值，因为所有操作最终都会通过一系列合并来修改它。 
2. 从左到右遍历数组，模拟每个元素最终都会通过某种合并序列与当前前缀进行交互。 我们不是模拟走法，而是根据回合奇偶性来推理每个元素是否可以主导当前值。 
3. 维护一个状态，表示当前有效操作的行为是否类似于最大步长或最小步长。 这种交替反映了乌龟和小猪交替移动的事实，并且随着时间的推移，这种交替通过收缩过程传播。 
4. 处理新元素时，根据当前奇偶校验状态取最大值或最小值来更新当前值。 这体现了这样一种想法：一个玩家将数值向上推，而另一个玩家将数值向下推，每个元素根据其在消除顺序中的位置而经历两种力量。 
5. 在每个步骤之后翻转状态，以反映沿着有效链折叠成交替影响的交替回合。 

处理完所有元素后，最终的跟踪值就是答案。 

关键的不变量是，在处理前 k 个元素后，维护的值等于在最佳解决该前缀内的所有交互后第一个元素的最佳可实现值。 每个新元素在正确的交替运算符下只贡献一次，并且未来的操作不能追溯性地改变先前解析的合并的效果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    cur = a[0]
    take_max = True
    
    for i in range(1, n):
        if take_max:
            cur = max(cur, a[i])
        else:
            cur = min(cur, a[i])
        take_max = not take_max
    
    print(cur)
```读取每个测试用例后，我们用第一个元素初始化结果，因为每个操作序列最终都会转换该位置。 然后，我们迭代数组的其余部分，交替应用最大更新和最小更新。 布尔标志编码当前在有效减少过程中哪个玩家的影响力占主导地位。 

交替更新是关键的简化：我们不是模拟基于邻接的删除，而是将整个游戏压缩为一次传递，其中每个元素在正确的操作类型下仅合并一次。

 ## 边缘情况

 对于像这样的输入`[5, 5, 5, 5]`，每次操作无论 max 或 min 都保持该值不变。 该算法在 max 和 min 之间交替，但两个操作在每一步都返回相同的值，因此不变量成立，最终答案仍然是 5。 

对于像这样的严格递减数组`[4, 3, 2, 1]`，第一个 max 操作没有任何害处，但接下来的 min 操作立即将值推低，并且交替稳定在 2，这与计算结果匹配。 

对于二元素数组`[x, y]`，只发生一次 max 操作，所以结果很简单`max(x, y)`，这与第一步之后立即结束的游戏一致。
