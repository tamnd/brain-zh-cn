 ## 解决方案
 ## 问题理解

 我们得到了一系列魔典，每个魔典都有两个属性：难度值和潜在值。 它们的购买顺序是固定的，并且是最终的决胜局。 

在每个$n$此刻，我们必须准确选择一本未使用的魔法书。 选择取决于情绪标志。 如果情绪为 1，我们会选择潜力最高的魔法书。 如果心情为 0，我们就会选择难度最高的魔典。 当几本魔典在主要标准上出现平局时，我们会通过优先选择次要属性较大的一本来解决平局，如果仍然平局，我们会选择较早购买的那本。 

选择一本魔法书后，它会被永久删除，然后我们对剩余的一组重复该过程。 

关键的困难在于选择规则在每一步都会发生变化，并且每次选择都会永久改变可用集。 这排除了任何尝试预排序一次并天真模拟的方法，而无需支持动态删除和在变化的比较规则下重复最大查询的结构。 

和$n \le 10^5$，任何在每一步扫描所有剩余项目的方法都会花费$O(n^2)$，太大了。 我们大概需要$O(n \log n)$。 

当多个魔典共享相同的主要属性时，会出现微妙的失败情况。 例如，如果两个项目具有相同的潜力和相同的难度，则较早的购买指数将具有决定性。 如果数据结构未在其顺序中显式编码，则它可能会返回任意元素，从而破坏正确性。 

另一个常见的陷阱是试图在不同步的情况下维护两个独立的优先级队列。 由于每个魔典都会被永久选择和删除，除非仔细过滤，否则陈旧的条目会累积。 

## 方法

 暴力模拟很简单。 在每一步中，我们都会扫描所有剩余的魔典，并根据情绪标记计算潜力或难度的最大值。 每次扫描需要$O(n)$，我们这样做$n$次，导致$O(n^2)$。 和$10^5$项目，这是按顺序$10^{10}$比较，这是不可行的。 

该问题的结构暗示了一个经典的动态选择任务：在不断变化的比较器下重复提取最大值。 关键的观察结果是，尽管比较器发生了变化，但每个查询仍然是具有不同排序规则的同一基础集上的最大值。 这可以通过维护相同项目的两个优先级视图来解决。 

我们将所有魔典存储在两堆中，一堆主要按潜力排序，另一堆主要按难度排序。 每个堆包含所有项目，但是当删除某个项目时，我们将其标记为不活动。 当从任一堆中提取时，我们会丢弃陈旧的条目，直到找到有效的条目。 这种惰性删除技术可确保正确性，而无需昂贵的删除操作。 

每个操作都变成$O(\log n)$摊销，并且每本魔典都被移除一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(n)$| 太慢了|
 | 具有延迟删除功能的两个堆 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们在所有魔法书上维护两个优先级队列。 一堆按潜力排序，按难度排序，然后按较早的指数排序。 第二堆按难度排序，按潜力排序，然后按较早的指数排序。 我们还维护一个布尔数组，标记魔法书是否已被使用。 

在每一步中，我们都会查阅心情标志并重复从相应的堆中弹出，直到找到尚未使用的魔法书。 

1. 构建两个包含所有魔法书及其索引和属性的堆。 第一个堆以负潜力、负难度和索引为键。 第二个以负难度、负潜力和指数为关键。 负号使用 Python 的最小堆实现最大堆行为。 
2.初始化一个数组`used`尺寸的$n$，全是假的。 这会跟踪是否已选择魔法书。 
3. 对于每一步$i$从 1 到$n$，读取心情标志。 这决定了要查询哪个堆。 
4. 如果心情为1，则重复从潜在堆中弹出，直到找到索引未标记为已使用的元素。 将其标记为已使用并输出其索引。 重复是必要的，因为早期的删除可能会在堆中留下过时的条目。 
5. 如果心情为0，则对难度堆执行相同的过程。 
6. 继续，直到消耗完所有魔典。 

它之所以有效，是因为每个堆始终代表整个原始集合的正确顺序。 尽管元素不会同时从两个堆中物理删除，但延迟删除可确保在遇到每个过时条目时准确地忽略它们。 由于每个魔法书都被标记为使用一次，因此无论在该步骤中查询哪个堆，它都会被恰好提取一次。 

平局打破规则直接编码到堆键中，确保任何比较歧义都得到与问题陈述一致的解决。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    p = list(map(int, input().split()))
    
    used = [False] * n
    
    heap_b = []
    heap_a = []
    
    for i in range(n):
        heapq.heappush(heap_b, (-b[i], -a[i], i))
        heapq.heappush(heap_a, (-a[i], -b[i], i))
    
    res = []
    
    for i in range(n):
        if p[i] == 1:
            while used[heap_b[0][2]]:
                heapq.heappop(heap_b)
            _, _, idx = heapq.heappop(heap_b)
            used[idx] = True
            res.append(idx + 1)
        else:
            while used[heap_a[0][2]]:
                heapq.heappop(heap_a)
            _, _, idx = heapq.heappop(heap_a)
            used[idx] = True
            res.append(idx + 1)
    
    print(*res)

if __name__ == "__main__":
    solve()
```该解决方案依赖于将两个比较顺序直接编码到堆键中。 潜在堆和难度堆是对称的，并且每个堆都通过次要属性和索引确保正确的平局打破。 

惰性删除循环至关重要：没有它，堆将返回已被其他模式消耗的元素。 每个 while 循环都保证堆顶在选择之前始终有效。 

通过在内部存储从零开始的索引并仅在输出时转换为从一开始的索引来仔细处理索引。

 ## 边缘情况

 一个关键的边缘情况是多个魔法书共享相同的主要和次要值。 考虑：```
a = [5, 5]
b = [5, 5]
p = [1, 0]
```除了索引之外，这两个项目没有区别。 堆键必须包含索引以保证确定性选择。 该算法存储`( -primary, -secondary, index )`，因此索引正确地打破了关系，并且第一个选择仅取决于心情而不是任意的堆行为。 

当一个魔法书在两个堆中都是最佳的但首先被另一个堆消耗时，就会出现另一个边缘情况。 因为两个堆都包含相同的索引，并且我们总是检查`used[]`，过时的条目将被安全丢弃。 例如，如果通过难度堆选择第 3 项，则它保留在潜在堆中，但会被跳过，直到逻辑上删除为止。 这确保了交替情绪的一致性，而不需要交叉删除。
