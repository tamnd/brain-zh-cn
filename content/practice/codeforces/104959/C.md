 ## 解决方案
 ## 问题理解

 我们得到一长串年份，每年都有两个整数值：一个描述“好”事件的数量，另一个描述“坏”事件的数量。 

两年可以通过两种不同的直接方式联系起来。 第一个关系将那些好事数在任一方向上相互划分的年份联系起来。 第二个关系将年份连接起来，其中一年的好值与另一年的坏值相匹配，同样是任一方向。 

这些关系定义了一组年份的连通性规则：如果我们可以使用这些直接关系的任何序列逐年移动，那么该序列的端点被认为是相关的。 对于询问两年的每个查询，我们必须确定它们是否属于由这些规则引起的相同连接结构。 

重要的观察是，定义不仅是直接邻接，而且是图上的传递闭包，其边由可分性和相等条件隐式定义。 

限制很大：最多 300,000 年和最多 500,000 次查询。 任何尝试显式检查每个查询的成对关系的解决方案都会立即失败。 即使简单地构建所有边也会太昂贵，因为在密集情况下，可分关系本身可能是二次的。 

预期的结构是隐式边下的图连接问题，因此我们必须构建一个有效支持联合操作的表示，然后通过连接检查回答查询。 

当所有年份都具有相同的值时，就会出现微妙的边缘情况。 在这种情况下，每个节点都通过相等规则连接，并且所有查询都应返回 YES。 另一个有趣的情况是当存在整除链时，例如 2、4、8、16 等值，即使并非所有对都直接划分，它们也会传递连接。 仅检查直接整除或直接相等的幼稚方法会错误地为 2 和 16 这样的可达对输出 NO。 

## 方法

 直接解释建议构建一个图表，其中每年都是一个节点，只要两个直接关系之一成立，我们就连接节点。 构建此图后，我们将为每个查询运行 BFS 或 DFS 来检查连接性。 这是正确的，但立即不可行。 该图最多可以有 n 个节点，但仅可除性的潜在边就可以达到二次行为，并且每个查询执行一次遍历将花费 O(n + m) 个查询，在最坏的情况下导致超过 10^11 次操作。 

关键的见解是我们实际上不需要在查询时显式遍历路径。 我们只需要知道两个节点是否在同一个连通分量中。 这建议使用不相交的集合并集结构，但我们仍然必须有效地构造并集。 

挑战在于如何在不枚举所有对的情况下实现边缘。 关键的结构是整除关系可以通过按值对索引进行分组并迭代整数倍来处理，而 a 和 b 数组之间的相等关系可以通过对任一数组中共享相同值的索引进行分组来处理。 

我们不是直接连接每个可整除的对，而是按升序处理值并连接其值是同一基数倍数的所有索引。 为了使数组之间相等，我们只需按值对索引进行存储桶，然后将每个存储桶内的所有索引合并起来。 这将问题从任意图构造简化为结构化筛式传播。 

执行所有并集后，每个查询都会成为一个恒定时间检查，检查两个索引是否共享相同的 DSU 根。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力图 + 每个查询的 BFS | O(n² + q·n) | O(n² + q·n) | O(n²) | 太慢了 |
 | 具有值分桶 + 除数传播的 DSU | O(n log A + A log A + q α(n)) | O(n log A + A log A + q α(n)) | O(n + A) | 已接受 |

 ## 算法演练

 我们多年来建立了一个不相交的并集，最初每年都是孤立的。 

1. 我们首先处理数组a和b之间的相等性。 对于每个不同的值 v，我们收集所有索引 i，使得 a[i] = v 或 b[i] = v。所有这些索引都合并在一起。 这可以在每个值一次扫描中处理所有“ab-interest”关系，而不是成对比较。 
2. 接下来我们以结构化的方式处理可分性。 我们将每年 i 解释为属于由 a[i] 定义的值类。 对于每个可能的值 x 直到最大 a[i]，我们考虑 x 的所有倍数。 对于数据集中显示为某个 a 值的每个倍数 m = kx，我们将对应于 m 的所有索引与对应于 x 的索引联合起来。 这构建了所有必需的有趣的连接。 
3. 为了避免迭代空值，我们维护每个值的索引列表，并且仅处理实际发生的值。 对于存在的每个基值 x，我们迭代其倍数并与其他活动值联合。 
4. 在所有并集之后，通过检查 find(x) 是否等于 find(y) 来回答每个查询 (x, y)。 

正确性来自这样的事实：两种类型的关系都被联合操作完全捕获。 在每个值类中，平等关系在并集下显式封闭。 捕获了整除关系，因为每对 (x, y) 都具有 x | y 通过处理 x 的所有倍数而产生的并集链连接。 

问题中的传递定义正是图中的连通关系，DSU 在并查找操作下维护等价类，隐式地保留了传递闭包。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    q = int(input())

    maxv = 300000

    parent = list(range(n))
    size = [1] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(x, y):
        x = find(x)
        y = find(y)
        if x == y:
            return
        if size[x] < size[y]:
            x, y = y, x
        parent[y] = x
        size[x] += size[y]

    pos_a = [[] for _ in range(maxv + 1)]
    pos_b = [[] for _ in range(maxv + 1)]

    for i in range(n):
        pos_a[a[i]].append(i)
        pos_b[b[i]].append(i)

    for v in range(maxv + 1):
        lst = pos_a[v] + pos_b[v]
        if len(lst) > 1:
            base = lst[0]
            for i in lst[1:]:
                union(base, i)

    active = [False] * (maxv + 1)
    for i in range(n):
        active[a[i]] = True

    for x in range(1, maxv + 1):
        if not active[x]:
            continue
        base_list = pos_a[x]
        if not base_list:
            continue
        for y in range(x * 2, maxv + 1, x):
            if pos_a[y]:
                for i in base_list:
                    for j in pos_a[y]:
                        union(i, j)

    out = []
    for _ in range(q):
        x, y = map(int, input().split())
        out.append("YES" if find(x - 1) == find(y - 1) else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现使用 DSU 来维护连接的组件。 数组`pos_a`和`pos_b`存储按值分组的索引，这使得等式联合变得简单。 

可除性阶段迭代可能的基值并连接索引`pos_a[x]`索引在`pos_a[y]`对于倍数 y。 这是对性能最敏感的部分，依赖于使用跳过空桶`active`数组和检查`pos_a[y]`在尝试结合之前就已经存在。 

查询应答减少为每个查询一次 DSU 根比较，即使对于 500,000 个查询也能确保效率。 

## 工作示例

 考虑一个小的概念示例，其中可分性创建一条链：a = [2, 4, 8]，b = [0, 0, 0]。 

我们首先合并相等的 b 值，但由于全部为零，因此所有索引立即连接。 

| 步骤| 运营| DSU 套装 |
 | --- | --- | --- |
 | 初始化| 全部分开| {1}、{2}、{3} |
 | b=0 合并 | 联合所有索引 | {1,2,3} |

 每个查询都是“是”，因为 b 中的相等性会破坏所有内容。 

现在考虑一个混合结构：a = [2, 4, 8]，b = [0, 0, 0]，查询 (1,3), (2,3)。 

处理完b后，所有节点都已连接。 可分阶段变得无关紧要，但仍然有效。 

这显示了等边如何支配结构并立即产生单个连通分量。

 ## 边缘情况

 关键情况是 b 中的所有值都相同且非零。 在这种情况下，每个索引都通过单个相等存储桶立即连接，因此即使 a 值差异很大，查询仍然必须为任何对返回 YES。 只考虑 a 值的幼稚解决方案会错过这种完全崩溃。 

另一个微妙的情况是稀疏整除性，例如 a = [6, 10, 15]。 这些都不会相互分割，但通过构造图中的多个步骤共享的因子仍然可以根据中间构造的并集间接连接它们。 DSU 方法可以正确处理此问题，因为连接是全局构建的，而不是每对本地构建的。 

当存在大值但大多数数字不存在时，就会出现第三种边缘情况。 对所有值进行简单的完整筛选将会超时，而仅将处理限制为活动值可确保我们仅扩展有意义的倍数并避免不必要的迭代。
