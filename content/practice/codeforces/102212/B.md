 ## 解决方案
 ## 问题理解

 爱丽丝得分准确`a`她每次比赛都得分，而鲍勃则准确得分`b`每次他上场比赛都会得分。 经过几场比赛后，他们的总得分相等。 任务是找到两个玩家可以获得的最小正分数。 

如果爱丽丝演奏`x`次，她的分数是`a * x`。 如果鲍勃玩`y`次，他的分数是`b * y`。 我们需要最小的正整数`c`为此，两者`a`和`b`划分`c`。 换句话说，问题是求最小公倍数`a`和`b`。 

两个输入值最多为`10,000`。 直接搜索每一个可能的分数可以达到`100,000,000`，它足够大，以至于在 1 秒限制下不宜进行线性搜索。 问题的结构为我们提供了一个常数时间算术解决方案。 答案本身也完全符合规定的限制，因为此范围内两个值的最大可能最小公倍数最多为`10,000 * 9,999 = 99,990,000`。 

有一些小情况可能会暴露粗心的实现。 用于输入`1 1`，答案是`1`，因为两名球员每场比赛都已经获得一分。 一个从开始搜索的实现`a + b`会错过最小值。 用于输入`1 10000`，答案是`10000`，因为每个正倍数`10000`也可除以`1`; 通过不正确的公式对称地处理这两个值可能会产生更大的结果。 用于输入`4 6`，答案是`12`， 不是`24`， 因为`12`已经可以被两个值整除。 这捕获了简单地将输入相乘而不是删除它们的共享因子的方法。 

## 方法

 一种简单的暴力解决方案可以生成可能的分数，直到找到一个可以被两者整除的分数`a`和`b`。 例如，从`1`，我们可以测试每个整数是否`c`满足`c % a == 0`和`c % b == 0`。 第一个这样的值必然是答案，因为每个较小的正值都已被拒绝。 

这个版本的问题是搜索范围可能非常大。 为了`a = 10000`和`b = 9999`，答案是`99,990,000`，所以检查每个整数`1`通过答案要求`99,990,000`迭代。 尽管每次迭代都很简单，但这远远超出了必要的工作量。 

我们可以通过仅考虑一个输入的倍数来缩小搜索范围。 如果我们测试`a`,`2a`,`3a`，依此类推，第一个也能被整除的倍数`b`是最小公倍数。 因为答案最多是`100,000,000`和`a`至少是`1`，这仍然需要大约`100,000,000`迭代时`a = 1`，所以它也不是最干净的解决方案。 

关键的观察是，共同的部分`a`和`b`不得重复计算。 让`g = gcd(a, b)`。 产品`a * b`包含了每一个因素`a`和`b`，但代表的因素`g`两者都出现。 将他们的产品除以`g`精确删除重复的部分，给出最小公倍数：`lcm(a, b) = a * b / gcd(a, b)`。 

暴力破解之所以有效，是因为它搜索具有两个整除属性的第一个数字，但会失败，因为它忽略了两个输入之间的算术关系。 观察到它们的共享因子可以用最大公约数来确定，这让我们可以直接计算相同的答案。

 ## 算法演练

 1. 阅读`a`和`b`，Alice 和 Bob 每场比赛获得的分数。 
2. 计算`g = gcd(a, b)`使用欧几里得算法。 gcd 恰好包含两个评分值共享的因素。 
3. 计算`a * b // g`。 这是最小公倍数，因为相乘`a`和`b`合并所有因子，而除以 gcd 会删除两次包含的因子。 
4. 打印结果值。 它是可以被两者整除的最小正分数`a`和`b`，因此两个玩家都可以通过整数次游戏来达到这个目标。 

### 为什么它有效

 让`g = gcd(a, b)`。 我们可以写`a = g * x`和`b = g * y`， 在哪里`x`和`y`是互质的。 自从`x`和`y`没有共同因子，包含两个输入所需的所有因子的最小数是`g * x * y`。 替代`x = a / g`和`y = b / g`给出`(a / g) * b`，这正是`a * b / g`。 该值可被两者整除`a`和`b`，并且任何公倍数必须包含相同的所需因子，因此不存在更小的正公倍数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

a, b = map(int, input().split())

g = gcd(a, b)
answer = a * b // g

print(answer)
```这`gcd`函数实现欧几里得算法。 在每次迭代中，这对`(a, b)`被替换为`(b, a % b)`。 在此变换下，公约数集合不会改变，并且第二值最终变为零。 剩下的第一个值是 gcd。 

计算完 gcd 后，代码将进行计算`a * b // g`。 整数除法在这里是精确的，因为`g`将两者分开`a`和`b`，所以它必然会划分他们的产品。 Python 整数也不会溢出，尽管这里最大的中间积只是`100,000,000`反正。 

可能的分数没有循环，因此不存在涉及答案本身的边界条件，也不存在相差一的问题。 输入保证为正，因此 gcd 也为正，并且不会发生被零除的情况。

def solve(inp: str) -> str:

 ## 边缘情况

 对于`1 1`，最大公约数是`1`，所以公式给出`1 * 1 / 1 = 1`。 该算法不假设答案必须大于任一输入，并正确返回可能的最小正分数。 

为了`1 10000`，欧几里得算法计算`gcd(1, 10000) = 1`。 结果是`1 * 10000 / 1 = 10000`。 这是有效的，因为每个整数都可以被整除`1`，因此 Bob 可以达到的第一个正分数对于 Alice 来说已经是有效分数。 

为了`4 6`，最大公约数是`2`。 公式给出`4 * 6 / 2 = 12`。 粗心的实现仅使用`a * b`会回来`24`，这是一个公倍数，但不是最小的倍数。 除以 gcd 正是消除重复因子的方法。 

为了`9999 10000`，最大公约数是`1`，因此没有需要删除的因素。 该产品是`99,990,000`，这是最小公倍数，也表明答案可以接近规定的上限`100,000,000`。 该算法直接处理该边界，而无需迭代数百万个较小的候选分数。
