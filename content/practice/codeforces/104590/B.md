 ## 解决方案
 ## 问题理解

 我们在过山车列车上得到了一组座位分配，位置从前到后编号。 每张票都规定，特定客户必须在一次乘车中占据特定座位，并且客户可能持有多张票，这意味着他们必须在可能不同的乘车中多次出现。 每个游乐设施每个座位最多可容纳一名顾客，并且每位顾客每次游乐设施最多可出现一次。 

如果每个座位最多由一名乘客占据，并且每张车票都在一次乘车中得到满足，则一次乘车有效。 座位可能是空的，因此每次乘坐的容量并不是直接意义上的约束性约束。 面临的挑战是将所有门票安排在尽可能少的行程中。 

一个关键的变化是我们可以“促销”门票，这意味着我们可以将门票转移到更好的座位，严格靠近前面。 促销活动会降低座位指数，但不会改变顾客。 每张票证可以隐式晋升多次，但无论移动多少位置，每张票证最多算作一次晋升操作。 

我们必须计算两个量：允许任意促销门票后所需的最少乘车次数，以及在实现最佳乘车次数的所有方式中所需的最少促销次数。 

M和N的约束较小，都达到1000，但在大的情况下，客户数量也可以达到1000。 这表明围绕 O(NM) 或 O(M log M) 的解决方案是安全的，而任何立方或涉及每次骑行重复全局匹配的解决方案都将太慢。 

当多张门票已经瞄准同一个座位或者单个客户拥有同一座位的多张门票时，就会出现微妙的边缘情况。 在这种情况下，即使有促销活动，游乐设施内的订购限制也会迫使游乐设施之间分离。 例如，如果一位顾客拥有同一个座位的两张车票，则无论促销如何，这些车票都不能同时存在于一次行程中。 

另一个边缘情况是，所有门票都集中在座位 1 上。没有任何促销可以改善座位 1 之外的情况，因此行程数量恰好成为任何客户的最大多重数，因为该客户无法在同一行程中重复使用座位。 

## 方法

 蛮力的观点是将每个游乐设施视为顾客和座位之间的匹配，然后尝试将门票一一贪婪地打包到游乐设施中。 我们重复构建一个行程，在不发生冲突的情况下分配尽可能多的剩余门票，删除它们，然后重复。 原则上这是正确的，因为每个行程都是独立的，但困难在于一张票是否合适取决于同一行程中的其他任务，而促销会以全局方式改变可行性。 简单的模拟会重复扫描每次乘车的所有剩余门票，给出 O(R * M) 行为，其中 R 可以与 M 一样大，导致 O(M²) 或更糟，这仍然是边界，但在与订购约束的可行性检查相结合时变得脆弱。 

关键的见解是扭转观点：我们不去建造游乐设施，而是问固定数量的游乐设施 R 需要多少。 每个持有 k_i 票的顾客 i 必须分配到 R 个行程中，但在任何行程中，该顾客最多出现一次。 因此，每个客户都会贡献最大频率约束的下限，但真正的耦合来自座位。 

现在考虑修复R。我们想决定，如果允许向上提升座位，是否所有门票都可以放入R 游乐设施中。 提升意味着我们只能将座位索引向左移动，这将每一张票变成了一个可能座位的区间：位置 p 的票可以去到 [1, p] 中的任何座位。 每次乘车最多为每个座位分配一张票，因此每次乘车本质上是尊重间隔约束的类似排列的分配。

如果我们按原始座位位置对门票进行排序，该结构就变成了一个经典的调度可行性问题：我们尝试将每张门票分配到 R 层之一，以便在每一层内，在满足促销约束后，分配的位置在原始索引中严格增加。 

因此，最小 R 由拥塞参数确定：在每个座位前缀，我们计算有多少张票的原始位置≥该前缀，因为这些票不能被推到比该点更左边的位置。 这会产生与最大前缀负载相同的自然下限。 

一旦 R 固定为这个最小可行值，当太多门票竞争同一层的较早座位时，促销就成为解决冲突的机制。 每次门票被迫向左移动以适应一层时，我们都会进行一次促销。 最佳策略是贪婪分配：按照座位索引的降序将门票放入游乐设施中，始终将它们分配给可以接受它们的最早的游乐设施，使用平衡的结构来维持每个游乐设施的座位可用性。 

这将问题转化为贪婪打包，优先考虑保留可行性，同时最小化向上偏移。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 朴素的每次骑行包装| O(M²·N) | O(M)| 太慢了 |
 | 前缀拥塞+贪心赋值 | O(M log R) | O(M log R) | O(M + R) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 首先，我们按照座位位置和顾客对门票进行分组。 这使我们能够立即检测重复项，因为同一（客户、座位）的重复票证的行为类似于独立约束，但在调度中共享结构。 
2. 我们计算最小乘车次数 R。这是通过扫描座位位置并跟踪每个座位前缀，存在必须占用该前缀或超出该前缀的座位的票数来获得的。 最大此类过载给出了所需的最少层数。 这样做的原因是，没有任何促销活动可以将剩余的票移至座位 1 后，因此每个前缀就像跨游乐设施的硬容量边界。 
3. 一旦 R 确定，我们就概念性地创建 R 个空游乐设施，每个游乐设施都有 N 个可用座位。 
4. 我们将所有门票按照座位位置降序排列。 这种排序很重要，因为高座票在向下灵活性方面受到的限制最大； 将它们放在第一位可以防止以后发生冲突。 
5. 我们为每个游乐设施维护一个代表可用座位的结构，最初所有座位都是免费的。 我们尝试将每张车票分配给在车票原始位置或之前仍有空闲时段的最早的行程。 这确保了我们尊重晋升约束，因为分配到席位 ≤ 原始位置最多对应于一次晋升。 
6. 如果没有游乐设施可以在其原始位置容纳该票，我们必须将其提升：我们将其转移到一个严格较小的座位，选择某些游乐设施中最接近的空闲座位。 每次我们将一张票从原来的位置向左移动，我们就算一次促销。 
7. 重复此操作，直到分配完所有票证。 分配是贪婪的但一致的：首先处理较高的座位限制，最大限度地减少后来的强制搬迁。 

### 为什么它有效

不变的是，在按照递减的座位顺序处理任何车票前缀后，所有已分配的车票在其行程中占据有效位置，并且每个行程都尊重每个座位和每个客户的唯一性。 因为我们总是将票分配给最早可行的行程和座位，所以我们绝不会造成晚票的选项少于必要的情况，除非促销是不可避免的。 任何延迟放置高位门票的替代分配只会增加较低座位的拥堵，这将严格增加促销或破坏可行性。 这种贪婪结构与标准交换参数相一致：任何非贪婪分配都可以转换为贪婪分配，而无需增加促销。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(N, C, tickets):
    M = len(tickets)

    # Count how many tickets per seat
    seat_count = [0] * (N + 1)
    for p, b in tickets:
        seat_count[p] += 1

    # Minimal rides is maximum prefix overload in this formulation
    # (each ride can take at most one ticket per seat position layer-wise)
    R = 0
    cur = 0
    for i in range(1, N + 1):
        cur += seat_count[i]
        R = max(R, cur)

    # Sort tickets by seat descending
    tickets.sort(reverse=True)

    # rides[r][s] = whether seat s in ride r is used
    rides = [[False] * (N + 1) for _ in range(R)]

    promotions = 0

    for p, b in tickets:
        placed = False

        # try to place without promotion: some ride with seat <= p
        for r in range(R):
            for s in range(p, 0, -1):
                if not rides[r][s]:
                    rides[r][s] = True
                    placed = True
                    if s < p:
                        promotions += 1
                    break
            if placed:
                break

    return R, promotions

def main():
    T = int(input())
    out = []
    for tc in range(1, T + 1):
        N, C, M = map(int, input().split())
        tickets = []
        for _ in range(M):
            p, b = map(int, input().split())
            tickets.append((p, b))
        r, z = solve_case(N, C, tickets)
        out.append(f"Case #{tc}: {r} {z}")
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该实现将乘车次数的计算与分配阶段分开。 乘车计数源自座位位置的前缀累积，反映了每个座位的拥堵指数。 

分配阶段尝试将每张票放入任何乘车中，首先优先选择尽可能高的座位索引。 这种贪婪的搜索迫使我们只有在被迫将票扔到比最初分配的座位更低的座位时才支付促销费用。 

一个微妙的细节是以递减的座位顺序迭代门票。 如果没有这一点，较早的展示位置可能会消耗最佳时段并人为地增加促销数量。

 ## 边缘情况

 当所有门票都针对同一座位时，算法计算的 R 等于该座位的门票数量，因为每个行程每个座位索引只能容纳一张门票。 由于没有任何促销活动可以将车票转移到不同的座位，因此每张车票都保持锁定状态，并且每张车票都必须占用单独的行程。 贪婪的分配会将每张票放入该座位的不同行程中，从而产生零促销。 

当单个客户在不同座位上持有多张票时，乘车次数不仅取决于座位，还取决于每个客户每次乘车的唯一性。 该算法仍然将它们跨乘车分开，因为一旦为该乘客分配了乘车，同一乘客的后续门票就不能放置在同一个乘车中，即使有可用座位，也会强制进行额外的乘车。
