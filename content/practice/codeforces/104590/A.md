 ## 解决方案
 ## 问题理解

 我们得到了一个组列表，每个组都有固定的人数。 每个组都必须按某种顺序提供服务，并且为一个组提供大小为 P 的整个巧克力包。根据需要打开包装，但有严格的限制：如果打开一个包并产生剩余部分，则在打开任何新包之前，这些剩余部分必须被后面的组完全消耗掉。 

每个组要么从新的包边界开始，要么在有剩余的块已经在等待时到达。 如果一组巧克力完全使用新鲜打开的包装，则被认为是“好”的，这意味着它根本不消耗任何剩余的巧克力。 我们的任务是对这些组进行排列，以最大化其中有多少是好的。 

关键的困难在于每个组的大小决定了模 P 的余数，并且这些余数通过在整个排序过程中演变的全局剩余状态相互作用。 由于 N 至多为 100，P 至多为 4，因此该结构足够小，我们可以直接推理状态，但仍然足够大，以至于简单的排列检查不可行。 

一种简单的方法会尝试组的所有排列并模拟剩余的过程。 那是N！ 排列，每次模拟的成本为 O(N)，即使 N = 20 也是完全不可行的。 

一种更微妙的失败模式来自贪婪排序。 例如，首先将所有组的余数为 0 感觉很安全，但实际上可能会浪费对齐剩余部分的机会，以便后面的组也恰好落在包边界上。 

## 方法

 关键的观察结果是，只有以 P 为模的群体大小对于剩余动态才重要。 当一组大小为 g 的组到达时，它会消耗当前剩余缓冲区中的 g 块。 如果之后缓冲区正好达到 0，则该组是“新鲜的”； 否则它会创建一个新的剩余剩余状态。 

因此，该过程是遍历以 P 为模的留数，其中每个组通过减去其以 P 为模的大小来转换状态。绝对大小并不重要，只有 g % P 才重要。 

由于P≤4，剩余物的状态空间很小。 我们可以定义一个动态规划，确定我们使用了每个残基类的多少个组以及当前的剩余状态是什么。 我们的目标是在为群体服务时最大限度地增加进入状态 0 的次数。 

蛮力观点将其视为残基类计数的排列 DP。 原始形式仍然很大，但会崩溃，因为状态仅是 (r0, r1, r2, r3) 计数加上当前余数，并且转换仅取决于选择下一个组类型。 

关键的减少是我们不需要完全排序，只需要在剩余周期的每个阶段消耗每个残留类别的数量。 这将问题转化为 O(N * P * N^P) 状态的小 DP 计数问题，这是可以接受的，因为 P ≤ 4 且 N ≤ 100。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 排列蛮力 | O(N!) | O(N) | 太慢了 |
 | DP 超过残留计数和剩余状态 | O(N^3) | O(N^3) | O(N^2) | O(N^2) | 已接受 |

 ## 算法演练

 我们将每个组的大小压缩为其模 P 的余数，因为只有这样才会影响剩余部分。

1. 我们计算从 0 到 P−1 有多少组属于每个残基类别 r。 这将问题简化为频率而不是身份。 
2. 我们定义一个 DP 状态，在其中跟踪到目前为止每个残基类有多少组已被使用，以及当前剩余状态是什么。 剩余状态是当前结转的巧克力块数量，始终在 0 到 P−1 之间。 
3. DP 转换考虑从仍有剩余组的任何剩余类别中挑选下一组。 如果当前剩余加上组大小是 P 的倍数，则该组被视为新鲜组并且剩余为零。 否则，我们将剩余更新为 (current + r) mod P。 
4. 我们迭代所有有效的 DP 状态，通过一次消耗一组来更新转换。 DP值存储了迄今为止获得的最大新鲜组数。 
5. 答案是使用所有组的所有状态的最大 DP 值。 

### 为什么它有效

 剩余状态完全捕获了连续组之间的唯一依赖关系。 由于包的使用仅取决于模 P 的运行余数，因此以相同余数结尾的两个历史是可以互换的。 DP 探索残基类别的所有可能排序，同时保留足够的状态信息，因此不会遗漏任何有效序列，并且不会将无效序列计为有效序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N, P = map(int, input().split())
        arr = list(map(int, input().split()))

        cnt = [0] * P
        for x in arr:
            cnt[x % P] += 1

        # DP state: (c0, c1, ..., cP-1, rem)
        from functools import lru_cache

        @lru_cache(None)
        def dp(c, rem):
            if sum(c) == 0:
                return 0

            best = 0
            for r in range(P):
                if c[r] == 0:
                    continue
                nc = list(c)
                nc[r] -= 1
                new_rem = (rem + r) % P

                gain = 1 if new_rem == 0 else 0
                best = max(best, gain + dp(tuple(nc), new_rem))

            return best

        start = tuple(cnt)
        print(f"Case #{tc}: {dp(start, 0)}")

if __name__ == "__main__":
    solve()
```该解决方案将每个组压缩为其模类。 递归 DP 探索这些类的所有有效顺序，同时保留剩余的余数。 记忆确保重复状态被计算一次。 

一个微妙的点是，状态包括剩余计数的完整向量，这是必要的，因为即使当前余数相同，剩余组的不同分布也会导致不同的未来可能性。 

## 工作示例

 考虑团体`[4, 5, 6, 4]`其中 P = 3。它们的残基是`[1, 2, 0, 1]`。 

我们从计数开始`(r0=1, r1=2, r2=1)`余数为 0。 

| 步骤| 状态 (r0,r1,r2) | 雷姆 | 选择 r | 新雷姆 | 新鲜|
 | --- | --- | --- | --- | --- | --- |
 | 1 | (1,2,1) | (1,2,1) | 0 | 0 | 0 | 是的 |
 | 2 | (0,2,1) | (0,2,1) | 0 | 1 | 1 | 没有|
 | 3 | (0,1,1) | (0,1,1) | 1 | 2 | 0 | 是的 |
 | 4 | (0,1,0) | (0,1,0) | 0 | 1 | 1 | 没有|

 这显示了排序如何影响我们遇到余数 0 的频率。 

现在考虑`[1,1,1]`P = 3，所有残数为 1。 

| 步骤| 状态| 雷姆 | 选择 r | 新雷姆 | 新鲜|
 | --- | --- | --- | --- | --- | --- |
 | 1 | (3) | 0 | 1 | 1 | 没有|
 | 2 | (2) | 1 | 1 | 2 | 没有|
 | 3 | (1) | 2 | 1 | 0 | 是的 |

 无论订购如何，只有一组可以是新鲜的，这证实了 DP 抓住了固有的局限性。

 ## 边缘情况

 如果所有组的大小均可被 P 整除，则每次排序都会产生一个新组。 DP 每一步都会立即将 rem 从 0 转换为 0，因此所有组都会被计数。 

如果所有组具有相同的余数，则只有一个组可以完成每 P 个步骤回到余数 0 的完整循环，并且 DP 自然会通过循环状态来强制执行该约束。 

如果存在混合残基，则排序很重要，但 DP 确保考虑所有可能的排序，因此局部贪婪决策无法消除全局最优排列。
