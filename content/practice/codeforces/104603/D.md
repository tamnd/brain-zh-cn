 ## 解决方案
 ## 问题理解

 我们为比赛提供了固定的结构：每场比赛都有$K$难度级别和级别$i$准确地要求$C_i$问题。 问题按最低可用级别分类：等级问题$d$只能分配到级别$d, d+1, \dots, K$。 每个问题最多只能使用一次，并且在一场比赛中只能占据一个级别。 

我们还有货源$P_i$等级问题$i$。 任务是最大化可以形成多少个完整的竞赛，其中每个竞赛必须根据$C_i$要求，使用可用的问题而不重用。 

核心难点在于，高等级问题灵活，可以服务于更高层次，而低等级问题则受到限制。 这会在各个级别之间创建类似流程的依赖关系，早期的决策会影响以后的可行性。 

约束条件达到$K \le 10^5$和值高达$10^9$，这会立即排除任何每场比赛的模拟。 即使试图一一贪婪地构建竞赛也会太慢，因为可能的竞赛数量也可能很大。 

当我们过于急切地分配低级问题时，就会出现幼稚贪婪分配的微妙失败案例。 

例子：```
K = 2
C = [1, 1]
P = [1, 1]
```粗心的策略可能会将 1 级问题分配给 1 级，将 2 级问题分配给 2 级，从而产生 1 场竞赛，这是正确的。 但如果我们扩展这个：```
K = 2
C = [1, 1]
P = [100, 1]
```如果我们贪婪地消耗第 1 级的 1 级问题并忽略它们的灵活性，我们仍然可能得到正确的答案，但在更复杂的分布中，这会导致更高级别的饥饿，因为低级问题应该保留给可以使用它们的最严格的级别。 

关键的困难是确保始终可以提供灵活的高年级问题来填补低年级问题所造成的空白。 

## 方法

 蛮力的观点是尝试一项一项地构建竞赛。 对于每场比赛，我们都会尝试从 1 级到 1 级$K$，始终选择一个仍允许分配的具有最小等级的可行可用问题。 这是正确的，因为它直接尊重约束，但在计算上是不可行的。 

每场比赛都需要扫描多个级别，每个级别可能需要搜索可用的可用问题等级。 在最坏的情况下，最多$10^5$水平和潜力$10^9$竞赛中，这种方法就变得不可能了。 

结构洞察力是翻转视角：我们不是构建竞赛，而是测试给定数字的可行性$x$。 如果我们想建立$x$比赛，然后等级$i$需要$x \cdot C_i$分配给级别的问题$i$，并且这些必须来自所有问题等级$d \le i$。 

这将问题转化为累积约束下的可行性检查。 我们正在有效地以可用位置的下限分配供应，这自然表明处理水平会增加顺序，并保持灵活的较高等级产能的过剩。 

关键的观察是，较高级别的问题总是可以向下“延迟”，但较低级别的问题不能向上移动。 所以我们从低到高进行处理，跟踪满足每个级别后还剩下多少可用的问题。 

然后我们二分搜索最大可行的$x$，因为可行性是单调的：如果我们可以构建$x$竞赛，我们还可以构建任何$x' < x$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 贪婪每场比赛模拟 |$O(xK)$|$O(K)$| 太慢了|
 | 二分查找+贪心可行性|$O(K \log \max P)$|$O(K)$| 已接受 |

 ## 算法演练

 ### 固定数量比赛的可行性检查$x$1. 各级别的规模要求$i$需要$need_i = x \cdot C_i$问题。 这代表了我们必须满足的总需求。 
2. 遍历关卡$1$到$K$，维护可用于当前或更高级别的可用问题的运行池。 
3.水平$i$，添加所有年级的问题$i$进入池中，因为它们现在可以用于级别$i$及以上。 
4. 努力满足$need_i$使用当前池。 如果池不足，请立即返回 false，因为后面的级别无法弥补此处的短缺。 
5. 达到等级后$i$，将任何未使用的池结转到下一个级别。 

这是有效的，因为较低的级别有更严格的要求：如果我们不能满足级别$i$，更高级别的重新分配无法修复它。 

### 对答案进行二分搜索

 1. 定义一个函数`ok(x)`使用上述过程检查可行性。 
2.二分查找$x$从 0 到一个大的上限。 自然界限是$\sum P_i / \min C_i$，但在实践中$10^9$对于长长的算术，缩放边界是安全的。 
3. 根据可行性移动搜索范围。 

### 为什么它有效

 可行性检查强制执行前缀一致性条件：在每个级别$i$，总可用供应量达到等级$i$必须足以满足总需求达到水平$i$。 由于较高级别的问题只能向下移动，因此任何有效的分配都必须满足这些前缀约束。 

这使得从低到高的贪婪积累既必要又充分：它匹配唯一存在灵活性的方向，因此未来的重新分配无法修复违反的前缀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(x, K, C, P):
    # current available pool of usable problems
    pool = 0
    
    for i in range(K):
        pool += P[i]
        need = x * C[i]
        
        if pool < need:
            return False
        
        pool -= need
    
    return True

def main():
    K = int(input())
    C = list(map(int, input().split()))
    P = list(map(int, input().split()))
    
    lo, hi = 0, 10**18
    ans = 0
    
    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, K, C, P):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1
    
    print(ans)

if __name__ == "__main__":
    main()
```该解决方案是围绕单个可行性函数构建的，该函数累积地处理所有问题等级。 关键的实现细节是运行`pool`，它代表当前等级边界之前的所有可用问题。 

减法步骤`pool -= need`至关重要：它强制每个问题只使用一次。 如果省略此步骤，我们将错误地跨级别重用容量。 

应用二分搜索是因为可行性是单调的$x$。 一旦无法形成一定数量的竞赛，由于需求的线性扩展，任何更多的竞赛也会失败。
