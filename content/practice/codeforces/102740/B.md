 ## 解决方案
 ## 问题理解

 整个过程从五名有名字的士兵排成一队开始。 总是给前线的士兵注射剂量。 该士兵创建了一个相同的克隆体，两个副本都移到了队列的后面。 任务是确定获得该勋章的士兵的姓名`n`th 剂量。 输入是这个无限剂量序列中的单个位置，输出是原始五个士兵的相应名称。 

约束条件`n <= 10^6`改变我们思考解决方案的方式。 逐个处理每个剂量的模拟是完全可以接受的，因为一百万次操作对于两秒的限制来说很小。 尝试构建大型数学结构或重复重建整个队列的解决方案会浪费工作。 我们只需要维护队列的当前顺序并为每个剂量执行一次操作。 

主要的边缘情况来自于士兵再次出现时的误解。 一个常见的错误是假设序列只是每五个位置重复一次。 例如：```
Input:
6
```正确的输出是：```
Ace
```在前五剂之后，每个原始士兵都被克隆了一次，所以队列是：```
Ace, Ace, Bolt, Bolt, Cameron, Cameron, Doom, Doom, Echo, Echo
```艾斯再次服用第六剂。 重复循环方法会错误地输出 Bolt。 

另一个边界情况是第一个可能的输入：```
Input:
1
```正确的输出是：```
Ace
```没有先前的队列状态需要考虑，因此必须正确处理第一个人，没有任何零索引错误。 

## 方法

 直接的做法就是模拟队列。 我们维持目前的士兵秩序。 对于每个剂量，我们都会移除第一个士兵，检查这是否是所请求的位置，然后将该士兵的两个副本附加到后面。 这完全按照流程进行，所以保证答案是正确的。 

其高效工作的原因是输入限制仅为一百万次操作。 所有操作后的队列大小最多为最初的 5 个士兵加上 100 万个新克隆，因此内存占用仍然很小。 

更复杂的方法可能会尝试在序列中找到模式。 队列确实具有有趣的增长特性，因为每次处理某人时，他们的副本数量都会增加，但在这里发现和维护这些模式是不必要的。 蛮力之所以有效，是因为最大操作数很小，而模式搜索会增加复杂性，而不会提高所需的性能。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(n) | 已接受 |
 | 模式推导| O(log n) 或 O(1) 取决于方法 | O(1) | O(1) | 不必要|

 ## 算法演练

 1. 将 5 个起始士兵存储在一个队列中。 该队列代表未来剂量分配的确切顺序。 
2. 重复克隆操作，直到`n`已达到第 th 剂量。 在每次迭代期间，移除前面的士兵，因为该士兵接受下一次剂量。 
3. 如果当前迭代次数为`n`，立即输出该士兵的名字。 不需要模拟未来的克隆，因为它们不会影响已经确定的答案。 
4. 否则，将被移除的士兵的两个副本追加到队列的末尾。 原来的士兵和新的克隆人都在最后等待，符合流程的规则。 

为什么有效：每次完成迭代后，算法存储的队列正是相同剂量后的真实队列。 最初两个队列是相同的。 每一步都会删除相同的前线士兵，并在最后插入相同的两个副本，因此不变式仍然成立。 当`n`发生删除时，算法返回接收真实数据的同一士兵`n`th 剂量。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n = int(input())

    q = deque(["Ace", "Bolt", "Cameron", "Doom", "Echo"])

    for i in range(1, n + 1):
        person = q.popleft()

        if i == n:
            print(person)
            return

        q.append(person)
        q.append(person)

if __name__ == "__main__":
    solve()
```使用双端队列是因为我们需要的两个操作都很高效：删除第一个元素并将元素添加到后面。 普通的 Python 列表会使从前面删除的成本很高，因为所有剩余元素都必须移动。 

循环开始于`1`而不是`0`因为问题要求第一剂作为位置`1`。 这可以避免在检查当前士兵是否是答案时出现差一错误。 

仅在检查答案后才执行克隆操作。 如果我们在检查之前附加克隆，队列状态将代表下一个时刻，而不是当前士兵收到剂量的时刻。

 | 测量| 复杂性 | 说明|

 | 空间| O(n) | 每次模拟剂量后，队列都会增加一个元素。 |

## 测试用例```python
import sys
import io
from collections import deque

def solve(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n = int(sys.stdin.readline())
    q = deque(["Ace", "Bolt", "Cameron", "Doom", "Echo"])

    ans = ""
    for i in range(1, n + 1):
        person = q.popleft()
        if i == n:
            ans = person
            break
        q.append(person)
        q.append(person)

    sys.stdin = old_stdin
    return ans + "\n"

assert solve("1\n") == "Ace\n", "sample 1"
assert solve("6\n") == "Ace\n", "sample 2"
assert solve("943\n") == "Cameron\n", "sample 3"

assert solve("2\n") == "Bolt\n", "second soldier receives the second dose"
assert solve("5\n") == "Echo\n", "last original soldier"
assert solve("10\n") == "Echo\n", "after the first doubling cycle"
assert solve("1000000\n") != "", "large input handling"

 ## 边缘情况

 对于`n = 1`，队列中只包含原来的五个士兵。 该算法在第一次迭代时删除 Ace，看到当前迭代等于请求的位置，并在修改队列之前返回 Ace。 

为了`n = 6`，重要的细节是前五个操作不会使队列保持不变。 每个士兵处理完后，后面都会添加两份。 Echo 收到第五剂后，队列变为：```
Ace, Ace, Bolt, Bolt, Cameron, Cameron, Doom, Doom, Echo, Echo
```第六个被移除的是艾斯。 该算法经过五次迭代后达到相同的状态并返回正确的结果。 

对于较大的值，例如`n = 1000000`，该算法不会尝试存储整个答案序列。 它只存储当前队列状态并一次执行一个所需的操作，因此运行时间随着输入大小线性增长并且保持实用。
