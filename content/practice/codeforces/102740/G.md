 ## 解决方案
 ## 问题理解

 我们有一个小写字母网格`n`行和`m`列。 删除一列意味着从每一行中删除该字符位置。 选择要删除的某些列后，由行形成的剩余字符串必须按从上到下的非递减字典顺序出现。 允许相等的相邻行。 

任务是删除尽可能少的列。 同样，我们希望保留尽可能多的列，同时保留所需的行顺序。 

网格尺寸小，兼具`n`和`m`最多`100`。 这排除了尝试列的每个子集的方法，因为最多有`2^100`的可能性。 解决方案围绕`O(nm)`或者`O(nm + something small)`很容易足够快。 

棘手的部分是字典顺序取决于两行不同的第一列。 对于一对行来说看起来不好的列可能对另一对行仍然有用，因此不能通过独立检查行来做出决定。 

考虑这个输入：```
2 3
med
bay
```这些行最初是`med`和`bay`。 自从`m`大于`b`，第一列已经破坏了顺序。 仅删除后面的列无法修复此问题，因此还必须删除第 2 列和第 3 列。 答案是：```
2
```仅对包含递减相邻字符的列进行计数的粗心实现可能会失败，因为它忽略了较早的列在字典比较中具有优先级。 

另一个边缘情况是所有行都已排序时：```
3 3
abc
abd
acd
```正确的输出是：```
0
```每列都应保留。 当相邻字符不同时删除列的解决方案会错误地删除有用的列。 

第三个重要的例子是平等：```
3 2
aa
aa
ab
```正确的输出是：```
0
```前两行相等，这是允许的。 错误的方法可能会将相同的行视为需要删除。 

## 方法

 直接的暴力方法将尝试保留所有可能的列集，构造结果行，并检查它们是否已排序。 这是正确的，因为它检查了每个可能的最终网格。 然而，有`2^m`可能的列选择。 和`m = 100`，这是不可能的。 

关键的观察是字典顺序比较只关心两行不同的第一列。 当从左到右处理列时，一些相邻的行对将被永久确定。 如果保留的列构成行`i`小于行`i+1`，那么后面的列就不能改变这种关系。 如果保留的列构成行`i`大于行`i+1`，必须删除该列，因为它立即违反了尚未决定的对之间的排序。 

蛮力之所以有效，是因为它会检查所有可能性，但会失败，因为选择的数量呈指数级增长。 观察到从左到右的词典编排决策可以贪婪地最终确定，从而将问题简化为网格的单次扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(2^m * n * m)`|`O(nm)`| 太慢了|
 | 最佳 |`O(nm)`|`O(n)`| 已接受 |

 ## 算法演练

 1.维护一个数组`fixed`在哪里`fixed[i]`告诉是否行`i`和`i + 1`已被先前保留的列确定为正确的顺序。 

此信息是必要的，因为一旦两行被较早的较小字符分隔，后面的列对于该对就不再重要。 
2. 从左到右处理列。 

对于当前列，检查尚未固定的每对相邻行。 如果上行中的字符大于下行中的字符，则该列将使最后的行无效，因此删除此列。 
3. 如果未删除该列，请使用它来完成一些行对。 每当未固定对的上部字符小于下部字符时，将该对标记为固定。 
4. 对每个移除的列进行计数并输出计数。 

为什么它有效：

 对于每对相邻的行，该算法都会查看用于词典比较的相同列序列。 在一对固定之前，每个处理的列都包含该对的相同字符。 第一个保留的角色不同的列永远决定了关系。 仅当算法以正确的顺序放置该对时，该算法才会保留这样的决定列。 如果某列将任何未决定的对以错误的顺序放置，则该列不能出现在任何有效答案中，因此删除它总是安全的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    fixed = [False] * (n - 1)
    removed = 0

    for col in range(m):
        bad = False

        for row in range(n - 1):
            if not fixed[row] and grid[row][col] > grid[row + 1][col]:
                bad = True
                break

        if bad:
            removed += 1
            continue

        for row in range(n - 1):
            if not fixed[row] and grid[row][col] < grid[row + 1][col]:
                fixed[row] = True

    print(removed)

if __name__ == "__main__":
    solve()
```这`fixed`数组存储相邻行比较的状态。 它的大小是`n - 1`因为每个条目代表一对`(row, row + 1)`。 

对于每一列，第一个循环检查保留该列是否会创建反转。 该检查仅考虑未完成的对，因为完成的对已由前面的列决定。 

仅当保留该列时才运行第二个循环。 它标记了在此列中正确排序的对。 这两个循环的顺序很重要。 在最终确定任何对之前，必须首先验证每个未确定对的列。 

不需要索引技巧，因为每次比较都是在相邻行之间进行，因此从`0`到`n - 2`覆盖所有可能的对而不超出网格边界。 

## 工作示例

 ### 示例 1

 输入：```
2 3
med
bay
```追踪：

 | 专栏 | 配对比较 | 决定| 删除计数 | 固定对|
 | ---| ---| ---| ---| ---|
 | 0 |`m > b`| 删除列 | 1 | 无 |
 | 1 |`e > a`| 删除列 | 2 | 无 |
 | 2 |`d > y`| 保留专栏| 2 | 行 0 < 行 1 |

 前两列使行无效，因此它们被删除。 最后一栏是无害的，将答案保留为`2`。 

### 示例 2

 输入：```
3 3
abc
abd
acd
```追踪：

 | 专栏 | 配对比较 | 决定| 删除计数 | 固定对|
 | ---| ---| ---| ---| ---|
 | 0 |`a=a`,`a=a`| 保留专栏| 0 | 无 |
 | 1 |`b<b`,`b<c`| 保留专栏| 0 | 第 0、1 行固定 |
 | 2 | 被忽视，被忽视| 保留专栏| 0 | 第 0、1 行固定 |

 第一列不决定任何事情，因为所有行都有相同的字母。 第二列建立了正确的顺序，最后一列不再相关。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(nm)`| 每个`m`对所有列进行检查`n - 1`相邻的行对。 |
 | 空间|`O(n)`| 仅存储相邻行关系的状态。 |

 最大网格尺寸仅为`100 x 100`，因此线性扫描很容易符合限制。 该算法避免了可能的列子集的指数数量。

 ## 边缘情况

 对于相反的两行情况：```
2 2
ba
ab
```该算法从没有固定对开始。 在列`0`，它看到`b > a`，因此该列被删除。 在列`1`，它看到了同样的问题`a < b`是正确的，因此保留该列。 输出是`1`？ 实际上，仅删除第一列后的行就变成了`a`和`b`，它们是有序的，所以正确的输出是：```
1
```这说明了为什么决策是逐列做出的，而不是假设每个看起来很糟糕的行都需要删除所有列。 

对于相等的行：```
3 2
aa
aa
ab
```第一列仅包含相同的字符，因此没有固定的字符对。 第二列有`a = a`和`a < b`，这修复了第二个比较。 没有删除任何列，答案仍然存在：```
0
```该算法可以正确处理相等性，因为字典顺序允许相同的行。 

对于单行：```
1 1
z
```没有要比较的行对。 每列都可以保留，所以答案是：```
0
```这`fixed`数组为空，循环自然不会执行无效访问。
