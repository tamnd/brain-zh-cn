 ## 解决方案
 ## 问题理解

 该问题描述了一个矩形杂货店地板，其宽度`w`和身高`h`。 可能的赛道都是矩形，其角点位于该楼层的网格线上。 从所有可能的矩形中统一选择一条轨道，我们需要其周长的期望值。 答案必须四舍五入到最接近的整数。 

输入仅包含两个维度，即商店的宽度和高度。 输出不是特定的矩形或概率值，而是可以生成的每个可能矩形的平均周长。 

尺寸最多为 1000，因此乍一看似乎可以直接枚举所有矩形，但选择数量的增长速度远远快于边长的增长速度。 有`(w + 1)`可能的 x 坐标和`(h + 1)`可能的 y 坐标。 矩形的数量是`C(w + 1, 2) * C(h + 1, 2)`，这大约是`10^12`当两个维度都很大时。 任何检查每个矩形的解决方案都是不可能的。 我们需要找到一种在常数时间内有效的数学简化方法。 

主要的边缘情况来自处理最小尺寸和正确解释随机选择。 一个常见的错误是假设平均宽度是`w`，但矩形端点是从网格线中选择的，而不是从连续范围中选择的。 

例如，与：```
Input:
1 1
```只有一个可能的矩形，即整个商店。 它的周长是：```
Output:
4
```连续近似会错误地建议较小的平均值，因为它忽略了矩形必须具有正整数网格宽度和高度。 

另一个例子是：```
Input:
2 2
```可能的宽度不是均匀分布的。 宽度 1 比宽度 2 出现的频率更高，因为间隔一个单位的网格线对更多。 预期周长为：```
Output:
5
```一个粗心的解决方案，仅将可能的长度平均为`1.5`碰巧在这里可行，但这种推理并不能概括。 正确的计算必须考虑每个可能的宽度有多少个矩形。 

## 方法

 一个简单的解决方案将生成每个可能的矩形。 对于每对 x 坐标和每对 y 坐标，我们可以计算周长并将其添加到运行总和中。 处理完所有矩形后，除以矩形数量即可得到期望值。 

这种方法是正确的，因为每个矩形被选择的概率相同。 然而，矩形的数量是巨大的。 和`w = h = 1000`，大约有`500500`x 间隔的选择和 y 间隔的相同数字，给出超过`2.5 * 10^11`矩形。 这远远超出了比赛时限所能处理的范围。 

关键的观察结果是 x 和 y 维度是独立的。 预期周长是预期宽度的两倍加上预期高度的两倍。 我们不需要考虑完整的矩形，只需要了解两条随机选择的网格线之间的平均距离。 

假设存储宽度为`w`。 有`w + 1`x 坐标编号为`0`到`w`。 矩形宽度是两个不同的选定坐标之间的差异。 所有可能距离的总和可以按距离值进行分组。 距离为`d`准确地出现`w + 1 - d`因为左端点可以从那么多位置开始。 

所有对的总距离为：```
1 * w + 2 * (w - 1) + ... + w * 1
```这简化为：```
w * (w + 1) * (w + 2) / 6
```可能的 x 区间数为：```
(w + 1) * w / 2
```将它们相除得到预期的宽度：```
(w + 2) / 3
```同样的推理给出了预期高度：```
(h + 2) / 3
```预期周长变为：```
2 * ((w + 2) / 3 + (h + 2) / 3)
```这是：```
2 * (w + h + 4) / 3
```整个问题简化为评估该表达式并执行正确的整数舍入。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(w²h²) | O(1) | O(1) | 太慢了|
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算预期周长公式的分子，`2 * (w + h + 4)`。 分母始终是`3`，因此将值保留为整数可以避免浮点精度问题。 
2. 将分数四舍五入到最接近的整数。 由于分母是三，所以永远不会有精确的平局`.5`，因此在整数除以三之前加一可以得到正确的舍入。 
3. 打印结果整数。 

为什么它有效：矩形选择中唯一的随机性来自于选择 x 坐标对和 y 坐标对。 期望的线性使我们能够独立计算每一方的平均贡献。 两条网格线之间的预期距离的公式考虑了不同宽度出现不同次数的事实。 由于每个矩形都由其 x 间隔和 y 间隔精确表示一次，因此结合两个预期长度即可得出准确的预期周长。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    w, h = map(int, input().split())
    ans = (2 * (w + h + 4) + 1) // 3
    print(ans)

if __name__ == "__main__":
    solve()
```输入部分读取两个商店维度。 只有一个测试用例，因此不需要循环。 

中间的表达式直接实现了推导公式。 它是使用整数而不是浮点算术编写的，因为即使对于简单的分数，浮点舍入也会引入错误。 

最后的除法执行四舍五入。 对于正值`x / 3`, 计算`(x + 1) // 3`正确舍入，因为小数部分只能是`0`,`1/3`， 或者`2/3`。 

不存在边界问题`w = 1`或者`h = 1`因为该公式仍然正确地表示了唯一可能的区间。

import sys
import io

def solve_input(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    w, h = map(int, sys.stdin.readline().split())
    ans = (2 * (w + h + 4) + 1) // 3
    sys.stdin = old_stdin
    return str(ans) + "\n"

# provided sample
assert solve_input("2 2\n") == "5\n", "sample 1"

# minimum dimensions
assert solve_input("1 1\n") == "3\n", "minimum case"

# all dimensions equal
assert solve_input("1000 1000\n") == "1336\n", "maximum symmetric case"

# different dimensions
assert solve_input("1 5\n") == "6\n", "thin rectangle"

# catches incorrect averaging of side lengths
assert solve_input("2 10\n") == "10\n", "uneven dimensions"
```| 测试输入| 预期产出 | 它验证了什么 |

 |`1 1`|`3`| 正确处理最小的网格。 |

 ## 边缘情况

 对于尽可能小的商店：```
Input:
1 1
```只有两条 x 网格线和两条 y 网格线。 唯一的矩形是整个商店，所以周长是`4`。 公式给出：```
2 * (1 + 1 + 4) / 3 = 4
```并且算法会返回准确的答案。 

对于一个维度固定的商店：```
Input:
1 5
```每个矩形的宽度必须是`1`，而高度则不同。 该算法不假设维度之间是对称的。 它分别计算每个维度的预期贡献并将它们加在一起。 

举个例子：```
Input:
2 2
```有九个网格点。 可能的 x 距离的可能性并不相同，因为距离 1 比距离 2 出现的频率更高。 使用距离加权和的推导捕获了这种分布，而可能宽度的简单平均值则不能。
