 ## 解决方案
 ## 问题理解

 我们有一条长长的一维走廊。 有些位置包含电击器装置，有些位置包含鬼魂。 消灭器可以消除任何幽灵，但能量消耗取决于它们之间距离的平方。 由于所有的灭杀器都可以独立使用，因此每个鬼魂都应该由距离它最近的灭杀器来处理。 所需的输出是每个鬼魂的这些最小平方距离的总和，取模 (10^9+7)。 

输入给出了电击器和鬼魂的数量，以及它们沿走廊的位置。 位置是整数，可以大到（10^7），而zappers和ghost的数量都可以达到（10^5）。 对于 (10^5) 个幽灵和 (10^5) 个 Zappers，检查每个可能的配对将需要 (10^{10}) 距离计算，这远远超出了两秒限制所允许的范围。 我们需要一个接近 (O((n+m)\log n)) 或更好的解决方案。 

主要的边缘情况来自这样的事实：最近的电击器可能不是第一个遇到的电击器，并且距离可能为零。 例如，如果输入是：```
1 1
5
5
```答案是`0`因为鬼魂已经上了电击器。 仅检查严格较小距离的解决方案可能会意外地错过这种情况。 

另一种情况是鬼魂位于第一个电击器之前或最后一个电击器之后：```
2 2
10
20
0
30
```正确答案是`200`，因为鬼影在位置`0`是距离`10`从第一个击杀者和幽灵所在的位置开始`30`是距离`10`从第二个电击器开始。 仅在两个灭弧器之间进行搜索的解决方案将会失败，因为这些鬼魂两侧都没有灭弧器。 

第三种情况是两个电击器距离相等：```
2 1
4
10
7
```答案是`9`，因为两个电击器都是距离`3`距离，成本为 (3^2)。 只要使用最小距离，任何决胜局选择都可以。 

## 方法

 直接的方法是将每个鬼魂与每个电击器进行比较。 对于每个幻影位置 (x)，我们计算所有 zapper 位置的 ((x-z_i)^2) 并保留最小值。 这是正确的，因为 zapper 选择是独立的，因此每个幽灵都可以单独优化。 然而，对于 (10^5) 个幽灵和 (10^5) 个 zapper，最坏的情况会执行 (10^{10}) 次比较和距离计算，这太慢了。 

使这个问题变得更容易的结构是所有对象都位于一条线上。 对电击器位置进行排序后，距离鬼魂最近的电击器必须是该鬼魂周围的两个电击器之一。 任何距离左侧比最近的左邻居更远的电击器甚至更远，同样的论点也适用于右侧。 

这将问题简化为二分搜索。 对于每个鬼魂，我们找到第一个位置至少位于鬼魂位置的击杀器。 那个击杀者是右边最接近的候选人。 排序数组中的前一个 zapper 是左侧最接近的候选者。 当两个候选者存在时，我们计算到它们的距离，并添加较小的平方距离。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了|
 | 最佳 | O((n+m) log n) | O((n+m) log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对所有电击器位置进行排序。 排序顺序允许我们使用二分搜索找到任何幽灵的最近可能的邻居。 
2. 对于每个幻影位置，找到该幻影在已排序 zapper 数组中的插入位置。 该索引指向位置不小于幽灵的第一个 Zapper。 
3. 检查该索引处的 zapper 是否存在。 这是右侧最近的电击器。 
4. 检查该索引之前的 zapper 是否存在。 这是左侧最近的电击器。 
5. 将可用平方距离中较小的一个添加到答案中。 对每个幽灵重复此操作，并对结果取模 (10^9+7)。 

只需要检查两个电击器的原因是生产线的顺序。 假设有一个鬼魂位于两个灭灯器之间。 从最近的左侧电击器向左移动只会增加距离，从最近的右侧电击器向右移动也会增加距离。 同样的推理也适用于所有灭杀器范围之外的鬼魂。 

工作原理：排序后，二分搜索位置将所有 zapper 分为幽灵左侧和右侧。 每组中最接近的元素是唯一可能的最佳选择。 同一组中的所有其他电击器距离较远，因此其平方距离不能更小。 由于该算法评估两个可能的最近邻居，因此它总是为每个幽灵选择最小的能量成本。 

## Python 解决方案```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m = map(int, input().split())

    zappers = []
    for _ in range(n):
        zappers.append(int(input()))

    ghosts = []
    for _ in range(m):
        ghosts.append(int(input()))

    zappers.sort()

    ans = 0

    for x in ghosts:
        idx = bisect_left(zappers, x)

        best = None

        if idx < n:
            d = x - zappers[idx]
            best = d * d

        if idx > 0:
            d = x - zappers[idx - 1]
            cost = d * d
            if best is None or cost < best:
                best = cost

        ans = (ans + best) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```排序后的 Zapper 列表是唯一需要存储的结构，因为幽灵可以独立处理。 这`bisect_left`调用返回可以在不破坏排序的情况下插入幽灵的第一个位置，这恰好给出了右侧的第一个 zapper。 

该代码在检查左侧候选之前先检查右侧候选，但顺序不会影响正确性。 边界检查是必要的，因为插入位置可以为零，这意味着没有左 zapper，或者它可以等于`n`，这意味着没有正确的灭杀器。 

使用整数计算平方距离。 Python 自动处理大整数，但每次加法后取模可保持累积答案有界并遵循所需的输出格式。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O((n+m) log n) | O((n+m) log n) | 排序需要 O(n log n)，并且每个幽灵执行一次二分搜索 |

 ## 边缘情况

 当鬼魂正好位于消灭器上时，二分搜索会发现该消灭器是正确的候选者。 计算出的距离为零，因此算法不添加能量。 为了：```
1 1
5
5
```排序后的 zapper 列表是`[5]`，搜索索引为`0`，而正确的候选人给出的成本为`0`。 

当鬼魂位于所有灭杀器之前时，搜索索引为`0`，所以没有剩下的候选者。 该算法使用第一个 zapper。 为了：```
2 2
10
20
0
30
```鬼魂在`0`只检查电击器`10`，给出 (10^2=100)。 

当幽灵在所有 Zapper 后面时，搜索索引将成为数组的长度。 该算法会跳过不存在的正确候选者并使用最终的 zapper。 鬼魂在`30`在同一示例中使用位置`20`，也花费 (10^2=100)。 

当鬼魂正好位于两个灭杀器之间时，两个候选者都会受到测试。 为了：```
2 1
4
10
7
```成本为 (3^2) 和 (3^2)，因此任一选择都会给出正确的最小值`9`。
