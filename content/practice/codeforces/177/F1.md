 ## 解决方案
 ## 问题理解

 我们得到了一组二分字符：$n$男人和$n$女性。 他们之间有$k$可能的婚姻对，如果这对夫妇最终在一起，每对都有一个积极的价值，代表着观众的喜悦。 有效的“脚本结果”是对这些对的任何选择，使得没有男人或女人出现在多于一对选定的对中。 换句话说，我们正在二分图中选择一个匹配。 

每个有效匹配的总值等于其边的权重之和。 如果我们列出所有有效的匹配项并按总和升序对它们进行排序，则系统会要求我们输出$t$按该排序顺序进行第 -th 次匹配。 

关键的结构细节是$k \le 100$，因此该图的边数非常小。 虽然$n$最多可达 20，解决方案完全受边数而非顶点数的限制。 

一个天真的误解是认为我们正在自由选择边的子集。 由于顶点冲突，该操作立即失败。 另一个常见的错误是假设我们可以通过按权重递增顺序贪婪地添加边来生成匹配。 这是行不通的，因为排序是基于匹配，而不是边缘。 

当多条边共享端点时，会出现微妙的边缘情况。 

例如，考虑：```
n = 2, k = 3
1 1 5
1 2 1
2 1 1
```匹配项是：

 空集 (0),

 (1,2) (1),

 (2,1) (1),

 由于共享顶点，(1,2)+(2,1) 无效。 

因此，两个不同的匹配可以具有相同的值，并且排序必须将它们视为单独的条目。 任何按值删除重复的方法都会产生错误的结果。 

另一个问题是匹配的数量是指数级的$k$，因此必须仔细构建枚举。 

## 方法

 自从$k \le 100$，我们可以将每条边视为一个二元选择：包含或不包含它。 强力解决方案枚举所有边子集，检查所选子集是否形成有效匹配，计算其权重并对结果进行排序。 这是正确的，但是要付出代价$O(2^k \cdot k)$，这远远超出了可行的范围$k = 100$。 

关键的观察结果是有效性仅取决于顶点冲突，并且$n \le 20$。 这表明不是通过边来压缩状态，而是通过顶点的占用来压缩状态。 

每个男人和女人都可以是自由的，也可以是配对的。 这最多给出$2n \le 40$顶点，因此位掩码表示是自然的。 每条边将一名男子与一名女子连接起来，因此每次匹配都对应于边的子集，并且约束条件是没有顶点出现两次。 

这成为一个经典的“按升序生成所有加权匹配”问题。 我们不是生成所有内容并排序，而是使用状态上的最佳优先搜索按排序顺序生成匹配。 

我们通过当前使用的顶点集和当前总权重来定义状态。 从任何状态，我们尝试添加任何不与已使用的顶点冲突的边。 使用优先级队列可确保我们始终首先扩展最小权重的部分匹配，从而有效地按权重递增的顺序生成匹配。 

自从$k$很小，可达状态的数量仍然是可管理的，特别是因为每条边在有效匹配中仅使用一次，并且顶点冲突修剪了大多数组合。 

我们还通过使用的顶点位掩码和当前选择上下文来记忆状态，这样我们就不会重新访问相同的配置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集 |$O(2^k \cdot k)$|$O(k)$| 太慢了|
 | BFS 优先于匹配 |$O(S \log S)$,$S$= 有效状态数 |$O(S)$| 已接受 |

 ## 算法演练

 我们将每个部分匹配视为包含已用顶点的位掩码和总权重的状态。 

1. 将每个男性和女性索引转换为单个统一的顶点索引系统。 男人是$0 \ldots n-1$, 女性是$n \ldots 2n-1$。 这允许单个位掩码代表所有冲突。 
2. 使用空匹配初始化优先级队列：未使用顶点，权重 0。这对应于空脚本。 
3. 反复从优先级队列中提取权重最小的状态。 这确保我们按照总体满意度递增的顺序处理匹配。 
4. 当一个状态被删除时，将其视为一个有效的匹配。 增加一个计数器。 如果这个计数器等于$t$，立即输出其重量。 
5. 对于提取的状态，尝试用每条边扩展它$(u, v, w)$。 我们只考虑位掩码中两个端点均未使用的边。 这保留了匹配约束。 
6. 对于每个有效扩展，使用更新的位掩码和更新的权重创建一个新状态。 将其推入优先队列。 
7. 为了避免重新访问相同的配置，请维护一个由位掩码和可选的边索引级数键控的访问集，以确保我们不会通过不同的边顺序重新生成等效状态。 

### 为什么它有效

 每个有效匹配对应于至少一个遵守顶点约束的边插入序列。 优先级队列保证在所有部分匹配中，总权重最小的总是先扩展。 因为所有边权重都是非负的，所以扩展状态永远不会产生比状态本身更小的权重匹配。 这确保了当弹出一个状态时，不存在看不见的具有较小权重的匹配，因此输出按全局排序顺序出现。 

## Python 解决方案```python
import sys
import heapq
input = sys.stdin.readline

n, k, t = map(int, input().split())
edges = []

for _ in range(k):
    h, w, r = map(int, input().split())
    h -= 1
    w -= 1
    edges.append((h, n + w, r))

# state: (cost, mask)
# mask uses 2n bits: men [0..n-1], women [n..2n-1]

start = (0, 0)
pq = [(0, 0)]
visited = set([0])

count = 0

while pq:
    cost, mask = heapq.heappop(pq)

    count += 1
    if count == t:
        print(cost)
        break

    for u, v, w in edges:
        if not (mask & (1 << u)) and not (mask & (1 << v)):
            new_mask = mask | (1 << u) | (1 << v)
            if new_mask not in visited:
                visited.add(new_mask)
                heapq.heappush(pq, (cost + w, new_mask))
```该代码将每个部分匹配编码为位掩码$2n$顶点。 这直接强制执行任何顶点不能出现两次的规则。 每次我们弹出一个状态时，我们都会将其视为按成本递增顺序的完整有效匹配候选者。 

重要的实现细节是我们仅通过掩码跟踪访问过的状态。 这是足够的，因为到达相同占用顶点集的任何两种方式都会导致该模型中等效的未来扩展可能性，因为一旦顶点被占用，边重用总是被禁止的。

 | 空间|$O(S)$| 优先级队列和访问集存储所有可达顶点掩码|

 ## 边缘情况

 一种边缘情况是所有边共享一个顶点，因此每个状态只能有一个匹配。 该算法自然地处理这个问题，因为任何扩展都会立即失败位掩码检查，只留下单例匹配和空集。 

另一个边缘情况是具有不同权重的重复端点。 由于每个边在输入中都是独立的，因此两者都被单独处理，并且位掩码不会折叠它们。 这确保了不同的匹配会被多次计数，即使它们产生相同的结构结果。 

最后一个边缘情况是$t = 1$。 优先级队列立即弹出空匹配，算法终止，不生成任何扩展，正确返回 0。
