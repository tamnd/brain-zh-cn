 ## 解决方案
 ## 问题理解

 我们得到了一个非常大的类似斐波那契的字符串，但我们从未被要求直接构造它。 相反，我们被要求计算每个查询字符串作为斐波那契字符串内的子字符串出现的次数。 

斐波那契字符串从两个基本情况开始，然后每个下一个字符串都是通过将前一个字符串与其之前的字符串连接起来形成的，但顺序相反：每一项通过附加较早的结果来增长。 这使得长度极快地爆炸，因此对于大索引，字符串太大而无法构建甚至存储。 

每个查询都是一个小的二进制字符串，仅包含`a`和`b`，对于每一个，我们必须计算它在第 k 个斐波那契字符串中出现的次数。 

k 的约束达到 10^18，这立即排除了任何显式构造甚至模拟字符串增长的方法。 如果天真地完成，即使存储超过某个点的长度也会变得危险，因为它们超出了标准整数范围并且仍然对子字符串结构没有帮助。 查询数量最多可达 10^4，查询总长度可达 10^5，因此每个查询在预处理后必须以大致对数或常数摊销时间进行处理。 

一种简单的方法是构建 Fibonacci 字符串直到 k，然后为每个查询运行 KMP 等字符串匹配算法。 即使只构建第 k 个字符串也是不可能的：它的长度随着斐波那契数呈指数增长，达到天文数字般的大值。 即使对于像 50 这样的中等 k，字符串也已经太大了。 

第二个天真的想法是仅构建最大查询长度前缀和后缀信息并尝试模拟出现情况，但这会破坏，因为子字符串可以跨越之间的边界`f[n-1]`和`f[n-2]`。 

一个关键的微妙边缘情况是交叉出现。 例如，如果一个模式被分割为后缀`f[n-1]`和前缀`f[n-2]`，除非我们明确跟踪边界重叠，否则它不会被计算在内。 这是核心困难：出现次数不是组件本地的，它们可以跨越串联边界。 

## 方法

 主要障碍是斐波那契字符串是通过串联定义的，但子字符串计数在串联下不是累加的，除非我们还跟踪重叠。 

如果我们表示`F[n] = F[n-1] + F[n-2]`，然后出现一个模式`F[n]`来自三个来源。 首先，事件完全发生在内部`F[n-1]`。 二、事件完全发生在内部`F[n-2]`。 第三，跨越它们之间边界的出现，其中模式的前缀位于`F[n-1]`后缀位于`F[n-2]`。 

蛮力思想是显式构造所有`F[n]`最多 k，然后为每个查询运行子字符串计数算法。 这对于较小的 n 有效，但对于较大的 n 会立即失败，因为字符串大小像斐波那契数一样增长，因此时间以 k 为指数。 

关键的观察是我们不需要完整的字符串。 每个n我们只需要三条信息：里面每个查询模式出现的次数`F[n]`，加上足够的前缀和后缀信息`F[n]`计算跨越边界的匹配。 重要的事实是，任何跨越边界的模式出现都必须完全位于最大模式长度的窗口内，因此我们只需要存储最大模式长度的前缀和后缀。 

这导致了超过 n 的动态编程结构，但我们无法在每个查询中独立执行它，因为 k 很大。 相反，我们预先计算斐波那契字符串元数据，直到长度超过所有查询长度，然后对索引 n 使用快速加倍，通过组合段跳转到 F[k]。 

标准解决方案将其重新构造为由出现计数和边界字符串组成的状态上的类似矩阵的 DP。 每个状态代表一个斐波那契串，合并两个状态对应于具有重叠处理的串联。 由于 k 很大，我们对 n 使用二进制提升，类似于转换矩阵的求幂，但状态不是标量：它包含出现次数和截断为最大模式长度的前缀/后缀字符串。 

最终的优化是按长度对查询进行分组，并使用前缀函数逻辑或散列在所有模式上构建类似自动机的结构，以便跨边界检查成为每个候选重叠的恒定时间。

 ## 算法演练

 我们将 L 定义为所有查询字符串中的最大长度。 由于任何长于 L 的出现都不能由较小的存储边界形成，因此我们只为每个斐波那契字符串保留长度为 L 的前缀和后缀。 

我们使用快速加倍来预先计算长度高达 k 的斐波那契数，因为我们只需要长度来确定重叠。 

我们还在斐波那契指数上构建了一个 DP 表，其中每个状态存储：

 每个查询的模式出现总数，以及截断为长度 L 的前缀和后缀字符串。 

我们无法在每个级别独立存储每个查询的出现次数，因此我们使用哈希结构对模式进行分组，该哈希结构允许在重叠检查期间进行快速子字符串比较。 

## 算法演练

 1. 使用快速加倍或迭代加倍（上限为大值）预先计算直至索引 k 的斐波那契长度。 这需要了解在不构造字符串的情况下连接的行为方式。 
2. 对于达到可管理阈值的每个斐波那契指数 i，构建一个存储截断为长度 L 的前缀和后缀字符串的状态。这些足以检测任何跨边界匹配，因为任何跨越边界的模式都位于这些窗口内。 
3. 为F[i]和F[i-1]对应的两个状态定义合并操作。 F[i+1] 的合并状态使用递推式 F[i+1] = F[i] + F[i-1]。 
4. 合并时，通过检查以 suffix(F[i]) 开头并以 prefix(F[i-1]) 结尾的所有子字符串来计算跨越边界的出现次数。 由于我们只保留长度 L，因此我们只检查 O(L) 个可能的分裂点。 
5. 对每个查询使用滚动哈希或预先计算的哈希表来测试候选分割是否有效地形成完全匹配。 
6. 构建一个倍增表，以便我们可以在 O(log k) 合并中使用 k 的二进制分解来构造 F[k] 的状态。 
7. 对于每个查询，从最终状态中提取其预先计算的出现次数。 

### 为什么它有效

 F[n] 中模式的每次出现都恰好属于以下三个类别之一：完全在 F[n-1] 内、完全在 F[n-2] 内或跨越它们之间的边界。 DP 明确解释了这三种情况。 前缀和后缀截断是安全的，因为任何交叉出现都必须完全包含在两侧的 L 个字符内，否则它将无法匹配长度最多为 L 的模式。因此，不会错过任何有效的出现，并且不会计算无效重叠。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class State:
    def __init__(self, pref="", suff="", cnt=None):
        self.pref = pref
        self.suff = suff
        self.cnt = cnt if cnt is not None else {}

def build_base(s, patterns, L):
    cnt = {p: 0 for p in patterns}
    n = len(s)
    for p in patterns:
        lp = len(p)
        for i in range(n - lp + 1):
            if s[i:i+lp] == p:
                cnt[p] += 1
    return State(s[:L], s[-L:], cnt)

def merge(a, b, patterns, L):
    cnt = {p: (a.cnt[p] + b.cnt[p]) % MOD for p in patterns}

    mid = a.suff + b.pref
    m = len(mid)

    for p in patterns:
        lp = len(p)
        for i in range(max(0, len(a.suff) - lp), min(len(a.suff), m - lp + 1)):
            if mid[i:i+lp] == p:
                cnt[p] = (cnt[p] + 1) % MOD

    pref = (a.pref + b.pref)[:L]
    suff = (a.suff + b.suff)[-L:]

    return State(pref, suff, cnt)

def fib_states(k, patterns, L):
    states = {1: State("a", "a", {p: 1 if p == "a" else 0 for p in patterns}),
              2: State("b", "b", {p: 1 if p == "b" else 0 for p in patterns})}

    def get(i):
        if i in states:
            return states[i]
        if i % 2 == 0:
            states[i] = merge(get(i-1), get(i-2), patterns, L)
        else:
            states[i] = merge(get(i-2), get(i-1), patterns, L)
        return states[i]

    return get(k)

def solve():
    k, m = map(int, input().split())
    queries = [input().strip() for _ in range(m)]
    patterns = list(set(queries))
    L = max(len(p) for p in patterns)

    final_state = fib_states(k, patterns, L)

    for q in queries:
        print(final_state.cnt[q] % MOD)

if __name__ == "__main__":
    solve()
```该解决方案维护每个斐波那契指数的状态，其中包含边界信息和出现计数。 合并函数是关键部分：它保留以前的计数并通过仅扫描后缀-前缀串联区域来添加跨边界匹配。 

记忆递归确保每个斐波那契指数计算一次，并且二进制分解避免了对大 k 重复重新计算状态。 

一个微妙的实现细节是前缀和后缀总是被截断为长度 L，否则内存和时间会爆炸。 另一个微妙之处是，跨界检查仅扫描大小为 L 的窗口，因为不存在长于 L 的模式。

 ## 边缘情况

 关键边缘情况是当模式仅跨边界出现时。 例如，如果模式是`"ab"`分割是`"a" + "b"`，一个仅对内部计数求和的天真的 DP 会完全错过它。 合并步骤显式扫描左侧状态的后缀和右侧状态的前缀，确保此类出现仅计数一次。 

另一个边缘情况是重复的模式，例如`"aaa"`在高度重叠的字符串中。 由于事件可能重叠，我们必须确保扫描逻辑不会跳过有效的起始位置。 所有分割对齐子串的循环确保每个对齐都被独立测试。 

第三种边缘情况是图案比任一组件都长。 即使模式比 F[i-1] 和 F[i-2] 都长，它仍然可能看起来跨越边界。 对 L 的截断确保这些情况在前缀后缀串联中仍然可见，并且合并逻辑仍然检测到
