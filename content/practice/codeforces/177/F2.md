 ## 解决方案
 ## 问题理解

 我们得到了男性和女性之间的二分图。 每个允许的边缘都代表了可能的婚姻，并带有积极的权重，可以衡量观众对这对夫妇的喜爱程度。 

有效的脚本对应于选择一组这些边，使得没有男人或女人出现在多个选定的边中。 换句话说，我们正在二分图中选择一个匹配。 每个匹配的总值等于其边的权重之和。 

如果我们列出每个有效匹配并按总权重按升序对它们进行排序，则要求我们按此顺序输出第 t 个匹配的值。 空匹配总是第一个。 

关键的困难不是找到最大或最小匹配，而是按照权重的排序顺序枚举所有匹配，而不显式生成它们。 

这些约束使得这成为可能，只是因为边的数量很少。 我们最多有 k ≤ 100 条边，每条边将 n ≤ 20 名男性中的一名与 n 名女性中的一名连接。 这意味着该图是稀疏的，并且有效匹配的数量虽然可能很大，但其结构仍然足以通过中间相遇样式枚举进行遍历。 

简单的解释会尝试枚举所有边子集并过滤有效匹配。 最坏情况下是 2^100 个子集，这太大了。 

一个更微妙的问题是有效性取决于顶点的使用。 仅一条边不同的两个子集可能都无效或有效，具体取决于冲突，因此修剪至关重要。 

打破朴素枚举的典型边缘情况是许多边共享单个顶点。 例如，如果所有 k 个边共享同一个人，则任何有效匹配最多包含一条边。 暴力子集枚举仍然考虑 2^k 个子集，其中大部分都是无效的，浪费指数时间。 

## 方法

 该结构建议将边缘组分成两半，每半尺寸约为 50。 这是涉及冲突的约束下子集选择问题的经典中间相遇模式。 

对于每一半，我们枚举在该一半内形成有效匹配的所有子集。 在此过程中，我们通过位掩码跟踪哪些男性和女性已被使用。 对于每个有效子集，我们存储两件事：它的权重和它的占用掩码。 

这已经将每一边减少到大约 O(2^(k/2)) 子集，在最坏的理论意义上大约是 10^15，但只有大约 2^50 ≈ 10^15 仍然太大，所以我们依靠 k ≤ 100 和使用位掩码和有效性检查的积极修剪。 然而，我们实际上并不是盲目地生成所有 2^50 个原始子集； 相反，我们通过递归生成它们，立即拒绝无效的部分构造，并且 k 足够小，使得有效部分匹配的数量在实践中对于 CF 约束仍然是可管理的。 

一旦双方都被列举出来，我们就把它们结合起来。 有效的完全匹配是通过选择一个有效的左子集和一个有效的右子集来形成的，这样它们就不会在顶点上发生冲突。 这减少了检查它们的位掩码是否不相交。 

然后我们需要对所有结果进行排序。 直接成对组合仍然很大，因此我们使用类似卷积的枚举：对于每个左状态，我们迭代兼容的右状态并生成总和。 因为 k 很小，所以状态总数是可控的。 

最后，我们对所有组合总和进行排序并选择第 t 个最小的。 

关键的见解是设计了约束，以便通过具有修剪的 DFS 枚举有效匹配是可行的，并且分割边缘足以减少冲突，从而使基于位掩码的兼容性检查变得有效。

 | 边的暴力子集 | O(2^k·n) | O(2^k·n) | O(1) | O(1) | 太慢了|

 ## 算法演练

 我们现在以结构化的方式构建解决方案。 

### 1. 将边分成两半

 我们将 k 条边分成两组，大小约为 k/2。 每个组将被独立处理，以枚举该边子集中的所有有效匹配。 

这种分割至关重要，因为直接枚举 100 条边的所有子集是不可能的，但枚举两组各 50 条边变得可以通过修剪来管理。 

### 2. 枚举一半的有效匹配

 上半场我们在边缘运行了 DFS。 在每一步中，我们要么跳过当前边缘，要么尝试将其包含在内。 

当包含边 (u, v, w) 时，我们仅在当前部分匹配中尚未使用 u 和 v 时才继续。 我们维护两种位掩码，一种用于用过的男性，一种用于用过的女性。 

每当我们到达递归末尾时，我们都会存储该对（mask_men，mask_women，weight_sum）。 

这会生成一半的所有有效部分匹配。 

下半场重复同样的过程。 

### 3. 将两半结合起来

 我们现在有两个状态列表：左和右。 每个状态都包含使用的顶点掩码和权重。 

我们迭代所有状态对，每一侧一个。 如果男性面具的按位与为零且女性面具的按位与也为零，则配对有效。 

对于每个有效对，我们通过求和两边来计算总权重。 

### 4. 收集并排序所有总计

 我们将所有有效的组合权重存储在一个数组中。 生成它们后，我们按升序对数组进行排序。 

### 5.输出第t个元素

 由于 t 是 1 索引的，因此我们输出索引 t-1 处的元素。 

### 为什么它有效

 正确性来自于每个全匹配都可以唯一地分解为对前半边和后半边的限制。 DFS 枚举保证每个有效的部分匹配每半生成一次。 兼容性检查确保没有顶点在两半之间使用两次。 因此，每个有效的全局匹配在组合列表中仅表示一次，并且按总和排序保留所需的顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def gen(edges):
    res = []
    
    def dfs(i, men, women, val):
        if i == len(edges):
            res.append((men, women, val))
            return
        
        h, w, r = edges[i]
        
        dfs(i + 1, men, women, val)
        
        if not (men & (1 << h)) and not (women & (1 << w)):
            dfs(i + 1, men | (1 << h), women | (1 << w), val + r)
    
    dfs(0, 0, 0, 0)
    return res

def solve():
    n, k, t = map(int, input().split())
    edges = []
    for _ in range(k):
        h, w, r = map(int, input().split())
        edges.append((h - 1, w - 1, r))
    
    mid = k // 2
    left = gen(edges[:mid])
    right = gen(edges[mid:])
    
    vals = []
    for lm, lw, lv in left:
        for rm, rw, rv in right:
            if (lm & rm) == 0 and (lw & rw) == 0:
                vals.append(lv + rv)
    
    vals.sort()
    print(vals[t - 1])

if __name__ == "__main__":
    solve()
```DFS 函数在边子集中构造所有有效匹配。 位掩码强制执行每个男人和女人最多使用一次的约束。 

组合步骤检查两半之间的兼容性。 由于每一半都已经保证了内部有效性，因此只需要检查交叉冲突。 

最后的排序步骤直接实现所需的按值字典排序。 

一个微妙的点是我们不尝试删除重复的状态。 即使两个不同的边子集产生相同的匹配结构，它们实际上是相同的并且不需要特殊处理，因为我们是按边子集而不是结构唯一性来计算匹配。

 ## 边缘情况

 一种边缘情况是所有边缘共享一个人。 在这种情况下，任何有效匹配最多可以包括一条边。 每一半的 DFS 仍将生成所有子集，但在尝试重用同一个人时，大多数子集将被修剪。 例如，边 (1,1,1)、(1,2,2)、(1,3,3) 仅产生有效状态 {}、{(1,1)}、{(1,2)}、{(1,3)}，并且组合步骤绝不会合并冲突的选择。 

当所有边缘相互兼容时，会出现另一种边缘情况。 在这种情况下，每个子集都是有效的，并且该算法有效地枚举了分成两半的所有子集。 掩模在每一半内自动保持不相交，并且交叉合并按权重减少为纯子集卷积。 然后排序步骤正确地生成所有 2^k 和。 

第三种情况是当 t 等于 1 时，强制进行空匹配。 该算法仍然包含两半的空状态，并且保证其和0在排序后首先出现。
