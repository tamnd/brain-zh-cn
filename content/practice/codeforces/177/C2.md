 ## 解决方案
 ## 问题理解

 我们有一组人，其中一些人通过友谊关系联系在一起，而另一些人则因为彼此不喜欢而发生冲突。 友谊是通过链传递的，因此友谊图中的连接组件表示如果我们决定包含该组的任何成员，则必须将其视为不可分割的组。 

目标是选择邀请的一部分人，以便同时满足三个约束条件。 首先，如果一个人被邀请，那么其友谊连接组件中的每个人也都必须被邀请，因为部分包含会破坏被邀请人的所有朋友都在场的要求。 其次，受邀团体中不得包含任何互相不喜欢的人。 第三，所有被邀请的人必须在友谊图中形成一个单独的连接组件，这意味着最终选择的集合必须完全位于一个友谊组件内。 

因此问题的结构变成：友谊边定义连接的组件，我们必须选择一个组件的子集，其并集是内部连接的并且内部没有不喜欢的边。 由于连通性已经由友谊决定，因此“单个连接组件”条件意味着我们无法选择多个断开连接的友谊组件，除非它们实际上通过友谊边连接，而根据组件的定义这是不可能的。 因此，最终的答案是去除由于不喜欢约束导致的不兼容选择后单个友谊分量的大小。 

限制因素很重要。 如果人数最多为 2000 人，则友谊图最多可以有 2000 个节点，边也可以达到类似的规模。 这排除了对所有人进行指数子集枚举，因为这大约是$2^{2000}$，这是不可能的。 然而，在线性时间内计算连接的组件是可行的，在组件级别处理约束也是可行的。 

一个幼稚的错误是忽略“必须包括所有朋友”的规则并尝试贪婪地在本地删除不喜欢的对。 例如，如果三个人形成友谊三角，其中两个人互相不喜欢，贪婪地删除一个端点可能仍然会违反连接性或强制不一致的部分选择。 当组件之间而不是组件内部存在不喜欢的边缘时，就会发生另一种微妙的失败情况，并且解决方案错误地丢弃单个组件而不是整个组件。 

## 方法

 关键的观察结果是友谊边定义了强制组：连接的组件。 一旦计算出组件，任何有效的邀请都必须包含整个组件或完全排除它们，因为部分选择会破坏好友的关闭要求。 

蛮力方法将尝试选择任何人的子集并检查有效性。 对于每个子集，我们将验证如果包含一个人，则包含其所有朋友，并且子集中不存在不喜欢的边缘。 这需要迭代所有子集并验证约束，导致粗略$O(2^n \cdot n)$或者更糟。 和$n = 2000$，这是完全不可行的。 

关键的简化是使用 DSU 或 DFS 将图压缩为连接的组件。 此后，每个组件都是一个“超级节点”，必须作为一个整体来看待。 个体之间的厌恶边缘会转化为成分之间的冲突。 如果组件内有任何不喜欢的边缘，则该组件完全无效并且无法使用。 组件之间，我们只需要保证不将不兼容的组件选择在一起即可。 然而，由于要求强制所有被邀请的人都通过友谊连接，我们最终只能选择一个有效的组件，因此答案减少到不包含内部不喜欢的最大有效连接组件。 

这减少了从友谊边构建连接组件的问题，然后检查每个组件是否存在由不喜欢的边引起的内部冲突。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对子集的暴力破解 |$O(2^n \cdot n)$|$O(n)$| 太慢了|
 | DSU / DFS 组件 + 验证 |$O(n + k + m)$|$O(n + k)$| 已接受 |

 ## 算法演练

 我们将友谊边缘视为定义连通性。 

1. 总体构建DSU结构$n$节点并联合所有友谊对。 这形成了连接的组件，其中每个组件都是一个候选组，如果选择，则必须完全采用该候选组。 我们使用 DSU 的原因是它提供近乎恒定时间的合并和高效的组件提取。 
2. 形成组件后，将每个节点分配给其组件代表。 在这个阶段，每个组件代表了被迫一起移动的最大一组人员。 
3. 创建一个结构来跟踪组件是否“坏”。 如果任何不喜欢的边连接同一组件内的两个节点，则该组件会变坏。 这一点至关重要，因为这样的组件永远无法被完全选择。 
4. 迭代所有不喜欢的对。 对于每一对，找到他们的 DSU 代表。 如果两个端点属于同一代表，则将该组件标记为无效。 
5. 计算每个有效组件的大小。 答案是所有未标记为无效的组件中的最大尺寸。 

### 为什么它有效

 友谊闭包迫使我们将每个连接的组件视为原子的。 任何有效的邀请集都必须是整个组件的联合，但由于所选集的所有成员必须通过友谊相互可达，因此该集不能跨越多个断开连接的组件。 这将选择压缩为仅选择一个组件。 

唯一剩下的约束是内部一致性：所选组件内部不允许有不喜欢的边缘。 因此，在所有不包含内部冲突的友谊成分中，我们选择最大的一个。 没有涉及多个组件的配置可以满足连接性，因此减少是准确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

def solve():
    n = int(input())
    k = int(input())

    dsu = DSU(n)

    for _ in range(k):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        dsu.union(u, v)

    m = int(input())

    bad = [False] * n

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        ru, rv = dsu.find(u), dsu.find(v)
        if ru == rv:
            bad[ru] = True

    for i in range(n):
        dsu.find(i)

    best = 0
    for i in range(n):
        if dsu.find(i) == i and not bad[i]:
            best = max(best, dsu.size[i])

    print(best)

if __name__ == "__main__":
    solve()
```DSU 用于将友谊结构分解为组件。 处理完所有联合后，每个根存储其组件的完整大小。 

不喜欢处理步骤是小心的：如果两个端点共享相同的根，我们只会将组件标记为坏组件。 不同组件之间的不喜欢并不重要，因为无论如何这些组件都不能部分地合并到单个连接集中。 

最终循环仅迭代 DSU 根并选择最大的有效分量。 

一个微妙的点是最终的路径压缩循环。 无需打电话`find(i)`对于所有节点，某些节点可能不直接指向根，并且在迭代时我们可能会错过根标识。 这确保了正确的根检测。

 ## 边缘情况

 一个棘手的情况是，当不喜欢的边缘在友谊组件内形成循环时。 该算法正确地处理了这个问题，因为它只检查是否存在这样的边，而不是有多少。 一旦发现单个内部冲突，整个组件就失效，这符合两个不喜欢的人不能共存的要求。 

另一种边缘情况是所有节点都被隔离。 在这种情况下，每个节点形成大小为 1 的组件，并且除非存在独立的不喜欢的情况，否则没有一个节点被标记为坏的，而这在约束下是不可能的。 算法正确返回 1。 

最后一个微妙的情况是不喜欢只连接不同的组件。 该算法完全忽略这些，这是正确的，因为在友谊约束下，这些组件永远不会合并到单个连接集中，因此跨组件冲突不会限制单个组件的选择。
