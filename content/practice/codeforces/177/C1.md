 ## 解决方案
 ## 问题理解

 我们有一群人，其中有些人是朋友，有些人互相不喜欢。 友谊形成一个无向图，而厌恶则形成另一组禁边。 任务是选择一个人的子集，使得两个约束同时成立。 

首先，如果一个人被邀请，那么其友谊连接组件中的每个人也必须被邀请。 这意味着我们不能在友谊图的连接组件内选择单个顶点，选择是在整个组件的级别。 

其次，在邀请组内，不允许有两个由不喜欢的边缘连接的人。 由于不喜欢是在个体之间定义的，这成为友谊成分之间的约束：如果成分 A 中的任何人不喜欢成分 B 中的任何人，则 A 和 B 不能同时被选择。 

最后的要求是所有被邀请的人在友谊图中恰好形成一个连接的组件。 由于我们已经必须包含整个友谊组件，这意味着我们正在选择一组友谊组件，其并集在由友谊边引起的组件图中连接。 

因此，问题归结为使用友谊图的组件。 每个组件都有一个大小，并且组件之间存在由不喜欢对引起的禁止边。 我们想要内部不包含禁止边的最大连通组件集。 

限制因素以特定的方式发挥作用。 当 n 达到 2000 时，O(n²) 或 O(nm) 解决方案就可以了，但任何对所有人子集呈指数增长的解决方案都是不可行的。 然而，组件的关键结构减少表明我们将在尺寸小得多的图上操作，最多 2000 个顶点，但组件通常要少得多。 

导致错误解决方案的天真的误解是尝试直接选择单个节点并随后检查约束。 例如，通过避免不喜欢的边来贪婪地选择节点会失败，因为友谊图中的连接会强制整个组件。 另一个微妙的失败是忽略添加节点可能需要添加其整个组件，这可能会突然引入冲突。 

## 方法

 暴力视角首先考虑选择任何人的子集，然后验证两个条件：所有友谊边都包含在子集组件内（友谊下的闭包），并且子集中不存在不喜欢的边，并且诱导的友谊结构是连接的。 这是 2ⁿ 子集的指数，对于 n 达到 2000 来说这是不可能的。 

关键的简化是友谊边强制将节点划分为连接的组件，并且每个组件都表现为一个原子单元。 一旦我们将图压缩成组件，每个组件的权重就等于其大小。 任何有效的解决方案都是对整个组件的选择。 

现在问题变成：我们有一个图，其节点是组件，边是组件之间不喜欢的约束，并且我们想要选择一个总权重最大的连通诱导子图。 这仍然很重要，因为连通性是原始友谊意义上的，不一定保留在不喜欢的补图中。 

然而，我们可以以不同的方式重新构建。 我们观察到有效答案必须完全位于友谊图的连接组件内，而不是直接搜索子集，因为如果我们选择多个友谊组件，它们仍然必须通过友谊边连接，除非它们已经连接，否则这是不可能的。 因此，最终选择必须包含在原始图中的一个友谊连接组件中，但由于组件已经对该图进行了分区，这意味着我们正在单个组件图中有效地工作。

在每个友谊组件内部，我们查看其内部结构：我们考虑该组件的诱导图，以及节点之间的附加禁止边。 任务变成：找到连接组件内最大的顶点子集，使得导出的子图保持连接并且不包含不喜欢的边。 

This is equivalent to removing vertices that break connectivity or introduce forbidden adjacencies. 这里的标准技巧是独立对待每个友谊组件，并尝试使用 BFS 或 DFS 从起始节点扩展有效集，确保我们永远不会包含违反不喜欢约束的节点。 

最佳解决方案是通过观察得出的，即在连接的友谊组件内，任何有效的解决方案本身都是一个没有禁止边的连接子图。 因此，我们可以尝试通过从每个节点开始 BFS/DFS 并在尊重约束的情况下贪婪地增长来找到此类子图的最大大小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解节点子集 | O(2ⁿ·n) | O(2ⁿ·n) | O(n) | 太慢了|
 | 组件+BFS扩展| O(n + k + m) | O(n + k + m) | 已接受 |

 ## 算法演练

 We convert the friendship graph into connected components first. 使用 DFS 或 BFS 为每个节点分配一个组件 ID。 

然后我们构建一个压缩结构，其中我们只关心两个节点是否在同一个友谊组件中以及它们不喜欢哪些节点。 

然后，我们独立处理每个友谊组件，因为没有有效的集合可以混合来自断开连接的友谊组件的节点，同时保持连接性。 

1. Run a DFS over friendship edges to assign each node to a connected component. 这对任何连接的解决方案中必须组合在一起的节点进行分组。 
2. 对于每个组件，收集属于它的所有节点。 该组件的候选答案将独立计算。 
3. 对于给定组件，构建友谊边（限制在组件内部）的邻接列表和不喜欢关系的映射。 
4. 尝试通过迭代每个节点作为潜在的起点来构建该组件内最大的有效连接子集。 
5. 对于每个起始节点，运行 BFS，仅通过不喜欢的边扩展到与已选择的节点不冲突的邻居。 
6.维护当前选择的节点集和禁止集，该禁止集跟踪由于不喜欢来自选择的节点的约束而无法添加的所有节点。 
7. 当尝试添加邻居时，仅在未禁止且添加保留连接可能性的情况下才添加。 
8. 跟踪所有启动中任何成功构建的有效连接子集的最大大小。 

### 为什么它有效

 Within each friendship component, any valid solution must be a connected induced subgraph. BFS 正是探索了这种导出的连通子图，同时强制执行兼容性约束。 由于每个连接的解决方案都有一些起始节点，并且来自该节点的 BFS 可以重现它（或受冲突约束的超集），因此尝试所有启动可以保证我们不会错过最佳连接的有效集。 不喜欢的约束在扩展期间在本地强制执行，确保不包含无效的对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())
    k = int(input())

    g = [[] for _ in range(n)]
    for _ in range(k):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    m = int(input())
    bad = [set() for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        bad[u].add(v)
        bad[v].add(u)

    comp = [-1] * n
    comps = []

    for i in range(n):
        if comp[i] == -1:
            q = deque([i])
            comp[i] = len(comps)
            cur = [i]
            while q:
                u = q.popleft()
                for v in g[u]:
                    if comp[v] == -1:
                        comp[v] = comp[u]
                        q.append(v)
                        cur.append(v)
            comps.append(cur)

    ans = 0

    for nodes in comps:
        sz = len(nodes)
        idx = {v: i for i, v in enumerate(nodes)}

        adj = [[] for _ in range(sz)]
        bad_local = [set() for _ in range(sz)]

        for v in nodes:
            for to in g[v]:
                if to in idx:
                    adj[idx[v]].append(idx[to])

        for v in nodes:
            for to in bad[v]:
                if to in idx:
                    bad_local[idx[v]].add(idx[to])

        def bfs(start):
            used = [False] * sz
            forbidden = [False] * sz
            q = deque([start])
            used[start] = True
            cnt = 1

            for x in bad_local[start]:
                forbidden[x] = True

            while q:
                u = q.popleft()
                for v in adj[u]:
                    if not used[v] and not forbidden[v]:
                        used[v] = True
                        cnt += 1
                        for x in bad_local[v]:
                            forbidden[x] = True
                        q.append(v)
            return cnt

        for i in range(sz):
            ans = max(ans, bfs(i))

    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先构建友谊组件，因为所有连接约束都在那里强制执行。 然后，相邻和不喜欢的关系被限制在每个组件内，以避免跨组件污染。 

BFS 函数维护一个禁止数组，该数组表示由于不喜欢已选择节点的约束而无法包含的节点。 每次添加一个节点时，我们都会将其所有不喜欢的邻居标记为禁止，以确保不会引入非法对。 

我们从每个节点尝试 BFS，因为从其他地方开始任意贪婪扩展可能无法达到最佳解决方案。 

## 工作示例

 考虑样本输入。 

我们有一个友谊图，它分为组件 {1,2,3}、{4,5} 和 {6,7,8,9}。 不喜欢的边存在于 1 到 6 之间以及 7 到 9 之间。 

对于组件{1,2,3}，任何节点的 BFS 都会完全扩展，因为没有内部不喜欢约束。 从节点 1 开始的表为：

 | 步骤| 队列| 选择| 禁止 | 行动|
 | ---| ---| ---| ---| ---|
 | 1 | [1] | {1} | 1 | 的邻居 开始 |
 | 2 | [2,3]| {1,2,3} | 不变| 全部展开 |

 这确认了完整的组件是有效的。 

对于 {6,7,8,9}，从 6 开始，我们包含 7,8,9，但禁止的约束会阻止包含冲突的端点，因为 7 不喜欢 9，从而阻止完全关闭。 

| 步骤| 队列| 选择| 禁止| 行动|
 | ---| ---| ---| ---| ---|
 | 1 | [6] | {6} | 不喜欢的节点 6 | 开始 |
 | 2 | [7,8,9]| 部分集 | 更新禁止| 扩张提前停止|

 这说明了为什么完整组件 {6,7,8,9} 即使已连接也是无效的。

 ## 边缘情况

 一个微妙的情况是，当友谊组件内部连接但不喜欢迫使它分解为更小的有效子集时。 例如，在不喜欢 (2,4) 的路径 1-2-3-4-5 中，从 1 开始 BFS 最终将包含 2，从而禁止 4。这可以防止完全遍历并产生较小但有效的连接子集，并由禁止的传播机制正确处理。 

另一种边缘情况是需要多次启动才能找到最佳子集。 从受限区域深处的节点开始的贪婪 BFS 可能会提前阻塞自己，而另一个起点会产生更大的有效扩展。 该算法通过显式尝试每个组件内的所有起始节点来处理此问题，确保不依赖于起始位置。
