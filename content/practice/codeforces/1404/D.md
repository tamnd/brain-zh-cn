 ## 解决方案
 ## 问题理解

 我们正在开发一个两人构建游戏，涉及 1 到 2n 的数字。 一名玩家首先将这些数字分成 n 个不相交的对。 之后，第二位玩家从每一对中选择一个数字。 分数是所选数字的总和，只有当这个总和能被 2n 整除时，第二个玩家获胜。 

不同的是，你可以选择自己扮演的角色，但无论对方如何反应，你的策略都必须保证胜利。 如果您作为第一个玩家玩，则必须构造对，以便有效选择的总和不能被 2n 整除。 如果您作为第二个玩家玩，您必须能够通过在每对中选择一个元素来响应任何配对，从而强制总和可被 2n 整除。 

关键限制是 n 可以大到 500,000，这排除了任何依赖于枚举配对或检查子集的策略。 任何解决方案都必须是线性或接近线性的，因为交互需要直接生成或处理 2n 个值。 游戏的结构强烈表明，只有集合 1 到 2n 的全局算术属性才重要，而不是任何组合搜索。 

当 n 很小时，尤其是 n = 1 或 n = 2 时，会出现微妙的边缘情况，其中关于配对或模块化平衡的不正确的贪婪推理可能看起来有效，但在对抗性选择下失败。 另一个常见的陷阱是假设角色之间是对称的，而实际上第一个玩家从根本上来说处于更有利的位置，因为他们控制配对结构而不仅仅是选择。 

## 方法

 暴力解释将尝试评估第一个玩家的所有可能的配对和第二个玩家的所有可能的选择，检查是否存在获胜保证。 对于每对 2n 个元素的划分，第二个玩家每对有 2 个选择，给出 2^n 种可能的选择。 即使修复配对，决定第二个玩家是否可以强制 2n 的倍数也需要检查所有这些子集。 这很快就会变成 n 的指数，即使 n 约为 20 也是不可行的。 

关键的结构见解是，第二个玩家的选择相当于在每一对内部分配一个方向：他们选择一个端点。 因此它们形成的总和是 n 个独立二元决策的总和。 第一个玩家有效地试图阻止这些受限选择的任何子集达到特定的模块化目标，而第二个玩家则试图保证可达性。 

这个问题简化为模算术上的经典平衡现象：所有数字 1 到 2n 的总和是固定的，配对控制第二个玩家在移动最终总和时有多少自由度。 关键的观察是，如果第一个玩家将数字对称地配对在 2n + 1 左右，即 (i, 2n + 1 - i)，那么每一对的总和都是相同的常数 2n + 1。这种严格的结构迫使每个选择都对应于从每个互补对中精确选择一个元素，并且所有所得的总和都会折叠成一组严格约束的值，以避免被 2n 整除。 

另一方面，如果您尝试扮演第二个玩家，交互器总是可以以阻止一致的模块化结构的方式对数字进行配对，从而无法保证所有可能配对的正确总和。 这种不对称性源于这样一个事实：第一个参与者在全局范围内定义结构，而第二个参与者则在局部做出反应。 

因此，解决方案是确定性的：始终选择扮演 First，并输出将 i 与 2n + 1 - i 配对的对称配对。

 ## 算法演练

 ### 选择第一时

 1. 决定以第一个玩家的身份进行游戏，无论输入 n 是多少。 这是最佳的，因为我们可以对所有对施加刚性结构。 
2. 对于从 1 到 n 的所有 i，将数字 i 与数字 2n + 1 - i 配对。 
3. 通过为每对的两个元素分配相同的标签，以所需的格式输出该配对分配。 

选择这种特定配对的原因是它强制围绕区间 [1, 2n] 的中点完美对称，这是使所有配对总和相同的唯一结构。 这种一致性消除了第二个玩家选择中可利用的差异。 

### 选择第二时（为什么要避免）

 如果我们尝试扮演第二，我们将需要一个通用的选择策略来对抗所有可能的配对。 然而，配对可能会将大量数字集中在一起或敌对地分配残基，从而无法稳定模 2n 的总和。 任何固定策略都可以通过翻转所选元素的模块化贡献的配对来打破。 

### 为什么它有效

 构建的配对确保每对的形式为 (i, 2n + 1 - i)，因此每对的总和为 2n + 1。第二个玩家的任何选择都从每对中精确选择一个元素，这意味着所选数字形成一个基于补码的系统。 关键结果是所选数字的总和始终采用 n(2n + 1) 减去固定补码和的形式，并且此结构可防止总和与 2n 的倍数对齐。 模块化的刚性来自于这样一个事实：补数取消了对之间的相对自由度，使得无法调整残差以达到 0 mod 2n。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    sys.stdout.write("First\n")
    
    # assign pair index i to numbers i and 2n+1-i
    # we need to output p_i for i in [1..2n]
    res = [0] * (2 * n + 1)
    
    for i in range(1, n + 1):
        a = i
        b = 2 * n + 1 - i
        res[a] = i
        res[b] = i
    
    sys.stdout.write(" ".join(map(str, res[1:])) + "\n")
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该实现直接对对称配对进行编码。 数组`res`为每个数字分配一个对索引，确保从 1 到 n 的每个索引恰好出现两次。 该循环每对运行一次，因此它在 n 中是线性的。 

交互设置中需要输出后刷新，以确保裁判立即收到配对。

 ## 边缘情况

 对于 n = 1，该结构产生一对 (1, 2)。 输出将两个数字分配给第 1 对，任何选择都会选择其中一个。 这是唯一可能的结构，并且它仍然满足有效分区所需的约束。 

对于 n = 2，我们得到对 (1, 4) 和 (2, 3)。 跟踪构造表明每个元素都是唯一分配的并且没有重复发生。 这是最小的非平凡对称情况，并证实了配对逻辑。 

对于较大的 n，对称性确保每个数字 i 与其补码 2n + 1 - i 恰好配对一次，并且不会重复使用任何索引。 该结构保持稳定，不依赖于任何分支逻辑，因此不存在改变行为的隐藏病态情况。
