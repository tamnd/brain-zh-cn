 ## 解决方案
 ## 问题理解

 我们得到一棵树，其加权边的权重为 1，加上一个额外的特殊边，称为连接两个固定顶点的门户$x$和$y$。 门户可以使用任意多次，并且每次使用的成本为 0。沿树边缘的移动每次遍历的成本始终为 1，并且边缘可以任意重用。 我们必须构造一条从任意顶点开始、在任意顶点结束并且至少访问每个顶点一次的游走。 目标是最小化所有遍历树边的总成本。 

关键对象不是一条简单的路径，而是通过一条零成本捷径增强的树上行走。 如果没有门户，这就是经典的“覆盖树遍历中的所有节点”问题，其中除了选定的起点和终点之外，最小连接子树中的每条边通常必须遍历两次。 门户通过以零成本有效识别两个顶点来改变结构，这可以打破部分树的遍历对称性。 

约束允许最多$5 \times 10^5$所有测试用例的节点总数，这立即排除了任何二次甚至$O(n \log n)$每个测试用例都需要进行大量预处理并具有较大的常数。 每个测试用例的预期解决方案必须是线性的，依赖于树 DP 或结构计数参数。 

当门户连接位于树的不同部分甚至相邻节点的节点时，会出现微妙的边缘情况。 例如，如果$x$和$y$由于是一条长链的相同边缘端点，门户可以有效地替代中心路径的重复遍历。 忽略度数奇偶校验效应或假设除端点之外的所有边都始终加倍的简单解决方案将导致计数过多。 

当最佳路径在“门户连接的组件”内开始或结束时，会出现另一种失败情况，因为门户可用于模拟选择不同的端点，而无需实际支付遍历成本。 

## 方法

 如果没有门户，访问树中所有节点的最小行走是众所周知的：您遍历包含所有节点的最小子树（即整棵树）中的每条边，并且除了沿选定的起始顶点和结束顶点之间的简单路径外，每条边都使用两次。 等价地，成本为$2(n-1) - \text{diameter contribution}$，因为您可以避免走回一条路径。 

暴力方法将尝试计算最佳的开始和结束对，模拟门户使用方式的所有可能性，并评估生成的类似欧拉的遍历成本。 这很快就变得不可行，因为即使选择端点也已经给出了$O(n^2)$可能性，并且门户引入了重复的状态转换，这需要子集或配置上的状态空间中的最短路径。 

关键的观察是，树结构使我们能够根据必须遍历两次的边数进行推理。 每条边都会被强制两次，除非它位于由门户引起的某些“捷径结构”上。 该门户有效地在两者之间创建了替代的零成本连接$x$和$y$，因此可以遍历以此连接为根的子树之间的任何路径，而无需支付一个方向的费用。 

思考这个问题的正确方法是考虑我们正在构建一个覆盖所有节点的连接步行，这相当于进行覆盖所有顶点的跨越多图步行。 成本是所选遍历结构中边数的两倍减去最佳“保存路径”的长度。 

该门户使我们能够精确地沿着之间的独特路径降低成本$x$和$y$在树上。 如果我们想象删除该路径，树就会分裂为多个组件，并且门户允许我们在该路径的端点之间自由跳转。 最佳保存对应于在连接最终欧拉路径中的端点时避免重新遍历该路径段。 

所以问题简化为计算之间的简单路径的长度$x$和$y$， 说$d(x,y)$，并从基线成本中减去它$2(n-1)$，因为由于零成本隐形传态，整条路径可以“走捷径”一次。 

这给出了一个直接的公式：$$\text{answer} = 2(n - 1) - d(x, y)$$我们只需要计算树中的距离，这可以通过每个测试用例的 BFS 或 DFS 来完成。 

下面总结了强力方法和最佳方法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 枚举所有游览和门户使用情况 | 指数| 指数| 太慢了 |
 | 带距离查询的树公式 |$O(n)$每次测试 |$O(n)$| 已接受 |

 ## 算法演练

 1. 根据输入边构建树邻接表。 这种表示形式允许有效地遍历距离计算。 
2. 计算之间的最短距离$x$和$y$在树中使用 BFS 从$x$。 由于所有边的权重均为 1，因此 BFS 可以正确生成最短路径距离。 
3.让$d$是之间找到的距离$x$和$y$。 
4. 计算在没有任何捷径的情况下访问树中所有节点的基线遍历成本，即$2(n-1)$。 这相当于在类似欧拉之旅的步行中遍历每条边两次。 
5. 减法$d$从此基线开始，以考虑门户消除在之间遍历路径的需要的能力$x$和$y$朝一个方向。 
6. 输出结果值。 

不明显的部分是为什么要精确减去$d(x,y)$是有效的。 该门户有效地允许我们替换对之间唯一树路径的一次遍历$x$和$y$零成本跳跃，这条路径正是$d(x,y)$边缘长。 

### 为什么它有效

 在访问所有顶点的任何行走中，除了位于所选起始到结束路径上的边之外，每条边都必须在每个方向上至少遍历一次。 这是覆盖树木的最小边缘行走的标准特征。 该门户添加了一个额外的零成本连接，其行为就像在之间添加了一条额外的边缘$x$和$y$。 在树中，添加一条边恰好创建一个循环，并且最佳欧拉行走可以避免回溯该循环的一侧。 因此，唯一可降低的成本是通过组合之间的树路径创建的独特自行车路径的长度$x$和$y$与门户边缘。 由于门户边缘的成本为 0，因此节省的成本等于之间的树距离$x$和$y$，得出公式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(start, adj, n):
    dist = [-1] * (n + 1)
    q = deque([start])
    dist[start] = 0
    while q:
        u = q.popleft()
        for v in adj[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)
    return dist

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, x, y = map(int, input().split())
        adj = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            adj[u].append(v)
            adj[v].append(u)

        dist = bfs(x, adj, n)
        dxy = dist[y]

        ans = 2 * (n - 1) - dxy
        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```BFS 在每个测试用例中运行一次$x$，这已经足够了，因为我们只需要到$y$。 由于图是一棵树，任何两个节点之间都存在一条简单路径，因此 BFS 距离直接给出该路径长度。 

公式步骤是完全确定解决方案的地方。 剩下的就是标准的树遍历基础设施。 

## 工作示例

 考虑一棵小树，其中$n = 5$，边形成一条链$1 - 2 - 3 - 4 - 5$，并且门户连接$x = 1$,$y = 5$。 

基准成本是$2(n-1) = 8$。 1和5之间的距离是4。 

| 步骤| 价值|
 | ---| ---|
 | n | 5 |
 | 基线 | 8 |
 | d(1,5) | d(1,5) | 4 |
 | 答案| 4 |

 这对应于使用门户来避免一次回溯整个链。 

现在考虑一棵树形如星形，中心为 1，叶子为 2、3、4、5，叶子 2 和 3 之间有入口。 

基线又是$8$。 通过节点 1，2 和 3 之间的距离为 2。 

| 步骤| 价值|
 | ---| ---|
 | n | 5 |
 | 基线 | 8 |
 | d(2,3) | d(2,3) | 2 |
 | 答案| 6 |

 这表明，即使门户连接叶子，节省的也正是通过中心的路径长度。 

这些示例证实了门户的唯一结构效应是减去其端点之间的树距离。

 ## 边缘情况

 一种边缘情况是当$x$和$y$是相邻的。 在这种情况下，距离为 1，所以答案变为$2(n-1)-1$。 BFS仍然正确返回1，减法反映只保存了一次遍历。 

另一个边缘情况是星形树，其中两个端点都是叶子。 BFS 距离正确地穿过中心，并且节省等于 2。假设叶子是独立端点的简单方法将错过这种间接路径结构。 

最后一个边缘情况是$n=2$。 该树有一条边，基线成本为 2，两个节点之间的距离为 1，给出答案 1。BFS 初始化必须正确处理小图而不跳过单条边，否则距离将保持 -1 并破坏公式。
