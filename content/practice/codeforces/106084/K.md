 ## 解决方案
 ## 问题理解

 我们被赋予了一个$n \times n$每个单元格包含一定数量的石头的棋盘，并且整个网格上的石头总数恰好是$n^2$。 目标配置非常严格：在所有操作之后，每个单元格必须恰好包含一颗石头。 

单次移动包括从某个单元格中取出一颗石头并将其放入同一行或同一列中的任何其他单元格中。 成本就是此类移动的次数。 我们不能一步任意移动一块石头，只能沿着它的行或列移动。 

任务是计算达到统一配置所需的最小移动次数。 

约束条件允许$n \le 500$，所以网格最多有$2.5 \times 10^5$细胞。 周围有任何解决方案$O(n^2)$或者$O(n^2 \log n)$很好，虽然任何立方体$n$会太慢。 

一个关键的边缘情况是网格已经正确。 例如，如果每个单元格已经恰好包含一颗石头，例如调整对角线分布以使每个单元格都有一颗石头，那么答案必须为零。 始终执行重新分配的简单方法可能会错误地计算不必要的移动。 

另一个微妙的情况是当石头大量集中在单行或单列时。 例如，如果一行包含所有$n^2$石头和其他东西都是空的，正确的解决方案必须仍然有效地工作，而不是模拟单独的转移。 

## 方法

 乍一看，这个问题感觉像是运输或流动问题。 相对于每个单元一颗石头的目标值，每个单元都有盈余或赤字。 一个自然的暴力想法是重复选择一个有多余石头的单元格，并将一个石头移向同一行或同一列中有赤字的单元格，每次更新计数。 这种贪心模拟在概念上很简单，但每次移动只能修复一个单位不平衡，并且在最坏的情况下可能会出现$O(n^2)$移动。 每一步还需要找到一个有效的目标单元格，因此简单的实现至少变得$O(n^3)$，这太慢了。 

关键的观察结果是行和列的移动使问题结构解耦。 一块石头不需要移动到它的行或列之外，这意味着我们可以在水平重新分布方面独立地对待每一行，在垂直重新分布方面独立地对待每一列。 我们不需要模拟实际的石头运动，只需跟踪每行和每列有多少盈余或赤字。 

每行都有净盈余或净赤字，定义为当前持有的宝石数量减去$n$。 由于总石数正好是$n^2$，所有行不平衡的总和为零。 凡有盈余的行必须发出棋子，凡有不足的行必须通过列移动接收棋子。 同样的逻辑对称地适用于列。 

关键的见解是，每个动作都有助于同时纠正行不平衡和列不平衡。 行或列内的移动可有效解决两个维度上一个单位的不匹配问题。 这将问题简化为计算必须移动多少个单位才能平衡所有行和列，并且最小移动次数等于行（或等效列）之间总绝对不平衡的一半。 

因此，该解决方案减少为计算行总和并对绝对偏差求和$n$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 模拟动作|$O(n^3)$|$O(n^2)$| 太慢了 |
 | 行不平衡聚合|$O(n^2)$|$O(n)$| 已接受 |

 ## 算法演练

 我们重新构建网格，使每一行的目标总和为$n$。 由于每个单元格必须以一颗石头结束，因此每一行必须完全以$n$石头。 

1. 计算每行棋子的总和。 这为我们提供了当前石子在行中的分布，而无需担心各个列。 
2. 对于每一行，计算它与目标值的距离$n$。 正差值意味着必须离开该行的剩余棋子，而负差值意味着该行需要接收棋子。 
3. 将各行之间的所有正差异相加。 这表示必须从多余行中移出的棋子总数。 
4. 答案正是这个和，因为每一步都可以被认为是通过允许的行或列转换将一个单位的盈余从有盈余的行转移到有赤字的行。 

步骤 4 背后的原因是，每一步都将总不平衡减少一排中的一个盈余单位和另一行中的一个赤字单位，因此计算总盈余已经计算出了必要操作的最少数量。 

### 为什么它有效

 每行都以相对于其所需最终状态的固定盈余或赤字开始。 由于每次移动都会保留石子总数，并且一次仅重新定位一个单位，因此任何操作都无法修复多于一个单位的行不平衡。 与此同时，每一单位的剩余最终都必须被消除。 因此，所有行的剩余总量是移动次数的下限。 

通过允许的移动进行行到行传输所暗示的结构表明，这一界限是可以实现的，因为每个剩余单元都可以路由到某个赤字单元，而无需将所需操作的数量增加到每单元一次以上。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
row_sum = [0] * n

for i in range(n):
    row_sum[i] = sum(map(int, input().split()))

ans = 0
for s in row_sum:
    if s > n:
        ans += s - n

print(ans)
```该代码仅关注行总和，这已经足够了，因为石子总数是固定的，并且每行必须精确地以$n$石头。 我们只累积正偏差，因为负偏差对应于将接收而不是发送石子的行。 

一个微妙的点是我们不需要显式检查列。 列赤字是隐式满足的，因为总盈余等于总赤字，因此平衡行会自动平衡列。 

## 工作示例

 考虑第一个样本：

 输入网格：$$\begin{bmatrix}
0 & 1 & 2 \\
0 & 2 & 2 \\
1 & 1 & 0
\end{bmatrix}$$行总和为$[3, 4, 2]$， 和$n = 3$。 

| 行| 总和| 目标| 剩余|
 | ---| ---| ---| ---|
 | 1 | 3 | 3 | 0 |
 | 2 | 4 | 3 | 1 |
 | 3 | 2 | 3 | 0（赤字）|

 总盈余为$1$，所以答案是$1$。 

这表明，即使多个单元不平衡，也只需重新安置一个单元即可恢复平衡。 

现在考虑一个集中的情况：$$\begin{bmatrix}
9 & 0 & 0 \\
0 & 0 & 0 \\
0 & 0 & 0
\end{bmatrix}$$行总和为$[9, 0, 0]$， 和$n = 3$。 

| 行| 总和| 目标| 剩余|
 | ---| ---| ---| ---|
 | 1 | 9 | 3 | 6 |
 | 2 | 0 | 3 | - |
 | 3 | 0 | 3 | - |

 总盈余为$6$，这意味着需要六步才能均匀分布棋子。 

这表明，即使所有棋子都以单行开始，该方法也能自然扩展。

 ## 边缘情况

 一种重要的边缘情况是网格已经有效。 用于输入```
2
1 1
1 1
```每行总和为 2，与目标匹配。 该算法计算出零剩余并立即输出 0，正确地避免了任何人为的移动。 

另一个边缘情况是极度集中，例如```
3
9 0 0
0 0 0
0 0 0
```这里行总和为 [9, 0, 0]，因此剩余为 6。该算法在没有模拟重新分配的情况下计算了 6 次所需的移动，这与每次移动只能修复一个不平衡单位的事实相匹配。 

最后一个微妙的情况是，分布在列之间倾斜，但每行平衡。 为了```
2
2 0
0 2
```行总和已经是正确的，因此即使列看起来不均匀，答案也是零。 该算法正确地忽略了列结构，因为行平衡已经编码了所有必要的移动约束。
