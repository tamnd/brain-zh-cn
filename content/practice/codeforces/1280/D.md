 ## 解决方案
 ## 问题理解

 我们有一棵树，其中每个节点代表一个“筑巢地”，其中包含两种昆虫：蜜蜂和黄蜂。 每一种昆虫都会投票支持自己的一方，因此蜜蜂总是对一个地区的蜜蜂数量做出贡献，而黄蜂总是对黄蜂数量做出贡献。 

我们必须将树准确地分成$m$连接组，其中每个组都是一个连接子图。 每个组都被视为一个村庄，在每个村庄内我们比较黄蜂总数与蜜蜂总数。 如果黄蜂严格超过蜜蜂，则该村庄被视为“丑黄蜂”的胜利，否则该村庄被视为“漂亮蜜蜂”的胜利。 目标是选择一个分区，最大限度地增加黄蜂赢得的村庄数量。 

每个村庄必须连接的结构约束迫使每个村庄对应于树中某些边切割的连接组件。 所以任务实际上是决定在哪里切割边缘以精确形成$m$连接组件，同时最大化总重量差异为有利于黄蜂的正组件的数量。 

约束足够大，任何尝试枚举分区甚至所有子树分割的解决方案都是不可能的。 和$n$每次测试和总数最多 3000$10^5$，任何三次或更差的测试方法都会失败。 这立即排除了尝试所有分区或在没有结构的节点子集上进行朴素 DP。 

一个关键的微妙之处是，黄蜂和蜜蜂总数完全相同的村庄不能算作胜利。 这会产生尖锐的阈值效应，而不是线性评分函数，这使得朴素的贪婪聚合变得不可靠。 

另一个微妙的情况是，分裂成更多的村庄并不总是有利的。 总体上失败的子树可能包含内部正片段，但错误地切割它可能会破坏其他地方的潜在胜利，因为切割必须尊重连接性并且组件总数是固定的。 

## 方法

 蛮力视角会尝试考虑所有切割边缘的方法，以便将树准确地分割成$m$连接组件，然后计算每个组件的分数。 边子集的数量呈指数增长$n$，甚至限制为有效的森林$m$组件仍然留下指数数量的配置。 计算分量和是线性的，因此这种方法变得非常大。 

问题的结构表明我们并不是真正选择任意分区，而是精确选择$m-1$要删除的边缘。 一旦删除边，子树就变得独立，其贡献仅取决于其内部的聚合值。 这自然地暗示了一个树DP，我们在其中计算每个子树可以实现什么，具体取决于我们在其中执行的切割次数。 

关键的观察是每个子树都可以独立处理，但子树之间的唯一交互是通过我们“花费”的切割次数。 这导致了子节点上的背包式DP：每个节点聚合其子节点的结果，决定分配给每个子子树的切割次数，同时最大化形成的“好”组件的数量。 

关键的简化是，对于任何连接的组件，只有总差很重要：$\text{wasps} - \text{bees}$。 如果该总和严格为正，则该组件是好的。 这使我们能够将每个子树视为产生一个可以合并的值，并将分割的子树切割成独立的候选者。 

因此，我们不是跟踪完整的分区，而是根据我们将子树分成多少个组件来跟踪子树中可实现的最佳获胜组件数量。

 ## 算法演练

 我们以节点 1 为树根。对于每个节点，我们计算一个 DP 数组，其中状态表示子树中有多少个节点被分成给定数量的连接组件，并且我们存储可以获得的获胜组件的最大数量。 

让$dp[u][k]$表示我们可以从 的子树中获得的获胜村庄的最大数量$u$如果它被精确地分割成$k$成分。 

1.初始化各个节点$u$以便$dp[u][1]$对应于子树根本没有被切割的情况。 在这种情况下，整个子树是一个组件，如果总计为 1，则其值为 1$w-b > 0$，否则为 0。这表示引入任何削减之前的基本情况。 
2. 对于每个孩子$v$的$u$，我们合并 DP$v$进入$u$。 此时，我们考虑在当前的部分解之间分配组件$u$和子树$v$。 这是一个经典的背包合并组件数量的方法。 
3. 在合并过程中，假设我们已经计算了部分 DP$u$，我们处理$v$。 如果我们分配$x$组件到$v$和$y$组件的当前状态$u$，那么总数就变成了$x+y$成分。 我们尝试所有的分割并更新获胜组件的最佳可实现数量。 
4. 合并步骤还考虑了之间的边是否$u$和$v$是否被切割。 如果被砍掉的话$v$作为一个单独的组件独立贡献。 如果不剪的话$v$的子树必须与$u$，这将组件数量减少 1 并合并它们的权重。 
5. 为了干净地处理这个问题，我们不仅按组件数量维护 DP，还维护合并状态的聚合总余额（黄蜂减去蜜蜂）。 合并两个部分时，如果它们保持连接，则会将它们的余额相加。 如果结果总和为正，则合并后的组件贡献一场胜利。 
6.处理完所有children后，$dp[u]$是完全计算出来的。 根的答案是最大值$dp[1][m]$。 

关键思想是，每次我们“切割”一条边，我们都会将组件数量增加 1，并且我们会获得一个新的独立候选者，其获胜仅取决于其总余额。 民主党本质上是在预算下决定削减哪些方面$m-1$削减。 

### 为什么它有效

 有效分区中的每个连通分量对应于删除一组边后形成的子树。 DP 确保通过背包转换，在子树之间分配切割的每种可能的方式都被恰好考虑一次。 由于每个组件的获胜条件仅取决于聚合值，而不取决于内部结构，因此 DP 状态足以捕获所有相关信息。 树结构保证不存在循环，因此一旦切边，子问题就是独立的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    b = list(map(int, input().split()))
    w = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    # dp[u] = list of (components, best wins, total balance)
    # we will store only best wins; balance tracked separately during merge
    dp = [None] * n
    total_balance = [0] * n

    def dfs(u, p):
        # initial: one component consisting of u
        cur = [(1, 1 if w[u] - b[u] > 0 else 0, w[u] - b[u])]
        total_balance[u] = w[u] - b[u]

        for v in g[u]:
            if v == p:
                continue
            dfs(v, u)

            nxt = {}
            # option 1: keep v as separate component(s)
            for c1, w1, bal1 in cur:
                for c2, w2, bal2 in dp[v]:
                    nc = c1 + c2
                    nb = w1 + w2
                    nxt[nc] = max(nxt.get(nc, 0), nb)

            # option 2: merge v into u as one component
            merged_bal = total_balance[u] + total_balance[v]
            merged_win = 1 if merged_bal > 0 else 0

            for c1, w1, bal1 in cur:
                nc = c1 + (dp[v][0][0] - 1)
                nb = w1 - (1 if bal1 > 0 else 0) + merged_win
                nxt[nc] = max(nxt.get(nc, 0), nb)

            cur = [(k, v, 0) for k, v in nxt.items()]
            total_balance[u] += total_balance[v]

        dp[u] = cur

    dfs(0, -1)

    ans = 0
    for c, wv, _ in dp[0]:
        if c == m:
            ans = max(ans, wv)

    print(ans)

t = int(input())
for _ in range(t):
    solve()
```该实现遵循将子 DP 状态合并到父级中的想法，同时跟踪形成了多少个组件。 递归自下而上构建DP。 棘手的部分是组件计数取决于我们是否剪切或合并边，并且通过直接添加子 DP 状态或将它们合并到父级的余额中来编码。 

主要的微妙之处是确保合并时组件数量保持一致。 与单独处理子子树相比，每次合并有效地减少了一个组件的数量，因为切边增加了组件数量，而合并则使它们保持连接。

 ## 边缘情况

 一个关键的边缘情况是当子树的总余额恰好为零时。 在这种情况下，将其合并到父级中不会产生获胜组件，但将其拆分仍可能会创建获胜子子树。 DP必须分别保留这两种可能性； 否则它会错误地将中性组件视为胜利。 

另一种边缘情况发生在$m = n$。 每个节点都必须成为自己的村庄。 该算法必须确保每个节点都被独立对待，并且获胜计数减少到计数节点，其中$w_i > b_i$。 任何意外强制至少一次合并的基于合并的逻辑都会被低估。 

最后一个微妙的情况是一条长链，其中交替的节点具有正余额和负余额。 局部最大值处的贪婪切割会失败，因为切割受到全局所需组件的确切数量的限制。 DP 通过全球分配削减来处理这个问题，确保只有在预算允许的情况下才能形成孤立的积极部分。
