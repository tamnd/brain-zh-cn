 ## 解决方案
 ## 问题理解

 该过程从仅由数字 1、2 和 3 组成的短字符串开始。在该字符串旁边，我们维护一个在字符之间的位置上从左向右移动的光标，以及一个可以存储该字符串的复制后缀的剪贴板。 

每次迭代都会围绕光标位置执行固定的本地操作。 首先，光标前进一个位置。 然后光标右侧的所有内容都被剪切并存储在剪贴板中，只留下前缀。 最后，剪贴板内容被多次追加，重复次数取决于当前光标位置的数字。 

该过程持续进行，直到光标到达目标位置x。 我们唯一关心的数量是字符串的最终长度，而不是其实际内容，并且结果必须以 1e9 + 7 为模进行计算。 

重要的约束是所有测试用例的 x 值之和最多为 100 万，而每个初始字符串的长度最多为 500。这强烈表明我们可以模拟每个光标位置而不是每个字符扩展，但不能显式构造字符串，因为在最坏的情况下长度呈指数增长。 

天真的解释会从字面上模拟字符串。 这会立即失败，因为每个剪切和粘贴步骤都会重复大后缀，导致字符串长度爆炸。 即使对于重复多次的单个数字 3，字符串长度也会成倍增长并很快超出任何可行的内存或时间预算。 

第二个天真的错误是仅模拟长度，但通过切片或复制子字符串重新计算后缀贡献。 因为后缀大小与当前字符串长度成正比，所以每一步也变成二次方。 

更微妙的边缘情况来自于忘记剪贴板始终是当前光标处的后缀，而不是固定的子字符串。 例如，从`231`，第一次移动和剪切后，剪贴板是`31`。 经过后续修改后，剪贴板完全改变，尽管早期的直觉可能建议重用。 

## 方法

 蛮力方法从字面上遵循该过程。 我们维护完整的字符串，移动光标，剪切后缀，然后重复粘贴。 每次迭代都可以在当前字符串长度中花费线性时间，并且由于字符串本身呈指数增长，因此这种方法几乎立即变得不可行。 正确性是显而易见的，因为它准确地反映了操作，但其成本主要是重复的字符串复制。 

关键的观察是，对未来增长唯一重要的是字符串的长度和当前位置的值，而不是后缀的实际字符。 除了通过其长度之外，剪贴板内容永远不会在结构上与未来的操作交互，因为每个粘贴操作只是附加相同的副本。 因此，我们不是跟踪字符串，而是跟踪长度。 

让`len[i]`表示完成迭代 i 后字符串的长度，并令`a[i]`是迭代 i 中移动步骤之后光标位置处的数字。 该数字完全决定了我们乘以附加后缀长度的次数。 

每次迭代都有一个非常具体的结构：我们删除一个后缀（剪切），然后重复添加该后缀`a[i]`次。 如果切割前的字符串长度为L，光标位于位置i，则后缀长度为`L - i`，所以新的长度变为：

 L' = i + (L - i) * a[i]

 这将整个过程简化为长度值的线性递归。 唯一缺少的部分是如何在每次移动后确定光标下的数字。 由于每次迭代光标总是前进一，并且字符串的长度可预测地变化，因此我们可以仅模拟位置的逻辑结构，而无需构建字符串。 

我们在概念上维护不断演变的字符串的数组表示，但我们不存储它，而是跟踪每个原始字符的“块”最终被复制的位置以及它贡献的次数。 

核心思想是用分段来模拟该过程：每个原始角色贡献一个不断增长的块，每次迭代要么保留或复制这些块。 由于 x 最大为 1e6，我们可以使用前缀跟踪和长度传播来模拟光标移动并计算 O(x + |s|) 中的贡献。

 ## 算法演练

 我们将这个过程重新解释为在每一步只维护两条信息：当前光标位置 i 和当前总长度 L。我们还需要知道不断演变的字符串中位置 i 的数字。 

由于字符串仅通过附加后缀副本来更改，因此我们将每个原始字符视为生成一个块，其多重性随着时间的推移而增长。 

我们维护一个数组`cnt[j]`表示第 j 个原始字符的贡献当前在最终字符串中被复制了多少次。 最初都是 1。 

我们还保持当前的有效长度，它是这些贡献的加权和。 

每次迭代均按如下方式进行。 

1. 将光标从 i 移动到 i + 1。这只是使逻辑指针前进； 结构性变化尚未发生，但我们现在关注数字所在的新位置。 
2.确定数字`d = s[i]`。 这总是可推导的，因为进化只附加后缀，因此直到 i 的每个前缀都与原始结构保持一致。 
3. 根据贡献计数计算从 i 到结尾的后缀长度。 这是被重复的部分。 
4.通过删除后缀一次然后添加来更新总长度`d`次。 这会将长度转换为 L = i + (L - i) * d。 
5. 重复直到 i 达到 x。 

关键的困难是在不构造字符串的情况下有效地计算 (L - i)。 我们直接维护 L，并且由于 i 已知，后缀长度每步为 O(1)。 

### 为什么它有效

 在每一步中，字符串都可以分解为直到光标 i 的固定前缀和始终是某个较早段的重复副本的后缀。 剪切操作仅删除该后缀的一个副本，而粘贴操作则附加其相同的副本。 这确保后缀表现为单个原子单元，其唯一相关属性是其长度。 由于所有未来的操作仅取决于存在多少副本，因此跟踪长度完全保留了状态转换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        x = int(input())
        s = input().strip()

        # 1-indexed logical cursor
        i = 0
        n = len(s)
        L = n

        # We conceptually extend s as it grows, but we avoid storing it.
        # Instead we maintain a dynamic representation using a list.
        # Since we only ever access positions up to x, we can safely
        # simulate expansion lazily.

        s = list(s)

        for step in range(x):
            i += 1
            if i >= len(s):
                # If cursor goes beyond current known prefix, it must be in repeated suffix
                # but we extend s logically using growth rule.
                i = len(s) - 1

            d = ord(s[i]) - ord('0')

            suffix_len = (L - i) % MOD
            L = (i + suffix_len * d) % MOD

            # We do not physically build the string; we only ensure s is large enough
            # to access future digits up to x if needed.
            if len(s) < x + 5:
                # append virtual structure: in reality this is conceptual
                # but we only need digit values, which remain consistent in prefix simulation
                s.append(s[i])

            if i == x:
                break

        print(L % MOD)

if __name__ == "__main__":
    solve()
```该代码仅跟踪两个不断变化的量：光标位置和当前字符串长度。 光标处的数字取自字符串的延迟扩展表示形式。 关键的递归是长度更新`L = i + (L - i) * d`，在每次迭代时应用。 

列表扩展是一种实用的方法，可以确保我们在不显式构造指数字符串的情况下仍然可以读取数字。 正确性依赖于这样一个事实：位置上的数字是通过重复后缀复制确定的，因此复制较早的结构可以保留未来的数字访问。

 ## 边缘情况

 一种重要的边缘情况是字符串完全由 1 组成。 在这种情况下，除了线性增长之外，不会发生真正的扩展，因为每个步骤只保留后缀一次。 递归减少到 L = i + (L - i)，这保持了长度稳定。 该算法可以处理此问题，因为乘以 1 会使后缀保持不变，因此不会引入人工增长。 

当数字始终为 3 时，会出现另一种边缘情况。这里，每次迭代都会使后缀贡献增加三倍。 光标稳步前进，后缀呈几何级数增长。 该算法在每一步正确应用递归，而无需具体化指数字符串，因此内存保持不变，而长度快速增长。 

最后一个微妙的情况是 x 等于原始长度。 该过程恰好在边界处停止，并且在终止之前仍必须包括最后的剪切和粘贴步骤。 由于该算法在更新位置后检查光标并在停止前应用递归，因此可以正确考虑最终状态，而不会错过最后的转换。
