[CF 452D - 洗衣机、烘干机、文件夹](https://codeforces.com/problemset/problem/452/D)

 **标签：** 贪心，实现
 **求解时间：** 1m 52s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们有一个三阶段的生产管道。 

每一件衣物都必须首先进行洗涤，然后在洗涤完成后立即转移到烘干机中，然后在干燥完成后立即转移到折叠机中。 同一阶段的机器是相同的，每台机器一次只能加工一件物品。 

“立即”二字是关键难点。 除非当时有烘干机可用，否则不允许完成洗涤。 同样，除非折叠机当时可用，否则不允许物品完成干燥。 我们可以随意推迟洗涤的开始时间，以便满足这些条件。 

输入给出了衣物的数量、每个阶段的机器数量以及每个阶段的处理时间。 我们必须计算所有项目完成所有三个阶段的最早时间。 

限制小得惊人。 最多有$10^4$项目和至多$1000$每个阶段的机器。 单独处理每个项目的模拟是完全可行的。 甚至一个$O(k \log k)$或者$O(k)$解决方案很容易足够快。 排除的是任何对时间进行分钟建模的方法，因为处理时间可能会达到$1000$完成时间可能会增长到数百万次。 

一个常见的错误是独立对待每个阶段。 

考虑：```
1 1 1 1 5 5 5
```答案是 15。一件物品需要花费 5 分钟洗涤、5 分钟干燥和 5 分钟折叠。 

一个更微妙的例子是：```
2 1 1 1 1 100 1
```粗心的解决方案可能会在时间 1 开始第二次清洗，因为清洗器变得空闲。 那是非法的。 第一件物品占用烘干机直到时间 101，因此第二件物品无法在时间 101 之前完成洗涤。必须延迟其洗涤，以保持烘干机在洗涤完成时刻可用。 

当折叠阶段成为瓶颈时，就会出现另一个陷阱：```
3 3 3 1 1 1 100
```所有三台洗衣机和烘干机均可立即使用，但只有一台折叠机。 几乎同时完成多个干燥操作是不可能的，因为每个完成的干燥操作都需要立即可用的文件夹。 必须在清洗阶段更早地调整时间表。 

主要挑战是可用性约束通过管道向后传播。 

## 方法

 蛮力观点是根据时间轴上安排事件来思考。 对于每件衣物，我们都可以搜索最早的洗涤开始时间，最终允许立即过渡到干燥和折叠。 这是正确的，因为一旦知道机器占用情况，系统就是确定性的。 

问题是搜索时间明显变得昂贵。 完成时间可能会变得非常长，并且反复向前扫描以查找有效时刻会导致不必要的工作。 

关键的观察是我们永远不需要穿越时间进行搜索。 重要的是每个阶段的机器在下一刻变得可用。 

假设我们已经安排了一些项目。 对于新商品，我们会选择最早可用的洗衣机。 设其可用时间为$w$。 

如果洗涤开始于$w$，该物品将在$w+t_1$。 这时候我们就需要一台烘干机。 在所有干燥机中，最早可用的干燥机决定了何时可以进行转移。 

同样，干燥完成后，我们立即需要一个文件夹。 

我们可以从折叠阶段向后思考，而不是向前安排阶段。 如果某个文件夹在某个时间变得可用$f$，那么为其进料的干燥操作必须完成不早于$f$。 该烘干操作又决定了洗涤何时可以完成。 

比赛中使用的优雅解决方案在每个阶段都保留了每台机器下次可用的时间。 对于每件衣物，我们都会采用最早可用的洗衣机、烘干机和折叠机。 这三个可用时间决定了该项目的最早可行开始时间。 安排好后，我们会更新机器的可用性。 

整个过程变成了机器释放时间的直接模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力时间线搜索 | 潜力非常大| O(1) | O(1) | 太慢了|
 | 机器可用性模拟| O(k) | O(n₁+n2+n₃) | 已接受 |

 ## 算法演练

 让`wash[i]`是下一次洗衣机`i`可用。 

让`dry[i]`下次烘干机`i`可用。 

让`fold[i]`是下一次文件夹`i`可用。 

最初所有值都为零。 

对于每件衣物：

 1. 找到可用时间最短的洗衣机。 
2. 找到可用时间最短的烘干机。 
3. 查找可用时间最短的文件夹。 
4. 让这些时间成为`w`,`d`， 和`f`。 
5. 计算允许立即转移到剩余阶段的最早清洗开始时间。 

洗涤结束于`start + t1`。 

那么必须有烘干机，所以：```
start + t1 >= d
```干燥结束于`start + t1 + t2`。 

那么文件夹必须可用，因此：```
start + t1 + t2 >= f
```洗衣机本身无法提前启动`w`。 

结合所有约束：```
start = max(
    w,
    d - t1,
    f - t1 - t2
)
```6. 使用此开始时间安排项目。 
7. 将所选洗衣机的下一个可用性更新为：```
start + t1
```8. 将所选烘干机的下一个可用性更新为：```
start + t1 + t2
```9. 将所选文件夹的下一个可用性更新为：```
start + t1 + t2 + t3
```10.记录该项目的完成时间。 答案是最后一个预定项目的完成时间。 

### 为什么它有效

 对于每个项目，我们都会选择每个阶段最早可用的机器。 计算的开始时间是同时满足所有三个资源约束的最短时间。 

洗衣机一定已经空闲了。 洗涤结束后，烘干机必须立即空闲。 干燥结束时，文件夹必须完全空闲。 任何较小的开始时间都会违反至少其中一个条件。 

安排一个项目后，三台选定的机器将被占用，直到相应的阶段完成时刻。 可用性数组始终表示每台机器可以接受另一个项目的最早的未来时间。 由于每个项目都是在与这些可用性一致的最早可行时刻安排的，因此模拟构建了全局最早的时间表。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    k, n1, n2, n3, t1, t2, t3 = map(int, input().split())

    wash = [0] * n1
    dry = [0] * n2
    fold = [0] * n3

    answer = 0

    for _ in range(k):
        iw = min(range(n1), key=wash.__getitem__)
        idr = min(range(n2), key=dry.__getitem__)
        ifo = min(range(n3), key=fold.__getitem__)

        w = wash[iw]
        d = dry[idr]
        f = fold[ifo]

        start = max(
            w,
            d - t1,
            f - t1 - t2
        )

        wash[iw] = start + t1
        dry[idr] = start + t1 + t2
        fold[ifo] = start + t1 + t2 + t3

        answer = fold[ifo]

    print(answer)

if __name__ == "__main__":
    solve()
```三个数组存储机器释放时间。 发布时间的意思是“这台机器从此刻开始可以接受新的项目”。 

对于每个项目，我们选择每个阶段发布时间最短的机器。 因为机器数量最多1000台，所以线性扫描就完全足够了。 

最微妙的部分是计算`start`。 

洗衣机的可用性强加了`start >= w`。 

洗涤结束后必须可以使用烘干机，以便`start >= d - t1`。 

干燥完成后，文件夹必须可用，以便`start >= f - t1 - t2`。 

同时取这三个值中的最大值即可满足所有约束。 

更新很容易出错。 清洗机在清洗完成后变得空闲，而不是在整个管道完成后。 同样，烘干完成后，烘干机也变得空闲。 只有文件夹仍然被占用，直到最终完成时间。 

所有算术都适合 Python 整数。

 ## 边缘情况

 考虑：```
2 2 1 1 1 100 1
```烘干机是瓶颈。 安排第一个项目后，烘干机一直被占用，直到时间 101。对于第二个项目，我们有：```
w = 0
d = 101
f = 102
```公式给出：```
start = max(0, 100, 1) = 100
```第二次洗涤被故意延迟，以便在烘干机可用时准确完成洗涤。 该算法输出 102，这是最优的。 

现在考虑：```
3 3 3 1 1 1 100
```第一项之后，文件夹被占用，直到时间 102。第二项获得：```
start = max(0, 0, 100)
```因此它仅在时间 100 开始洗涤。第三个项目在时间 200 开始。完成时间变为 102、202 和 302。 

仅跟踪洗衣机和烘干机可用性的解决方案会错误地尝试在折叠机可用之前烘干多个物品。 后向约束`f - t1 - t2`防止这种错误。 

最后，考虑：```
4 1 1 1 10 1 1
```洗衣机是瓶颈。 当洗衣机空闲时，每个新物品都会自然开始。 该公式减少了对洗衣机的限制，因为烘干机和折叠机始终可以及时使用。 该算法的行为与简单的单机管道完全相同，并生成正确的时间表。
