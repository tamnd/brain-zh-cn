 ## 解决方案
 ## 问题理解

 我们正在构建一个数字序列$b_1, b_2, \ldots, b_n$代表每个好友会赠送多少张心愿卡，但每个好友都有上限$a_i$，以及所有$b_i$合计不能超过总预算$k$。 每个$b_i$必须留在$0 \le b_i \le a_i$。 

每个朋友之后$j$结束后，小A查看了目前为止所有的礼物，只记住了她看到的最大的价值，$\max(b_1, \ldots, b_j)$。 她一步后的幸福$j$正是那个最大值。 最终分数是所有这些前缀最大值的总和$j$。 

结构很重要：一旦出现一个大值，它就会不断对未来的每个前缀做出贡献。 如果我们设置一个值$x$在位置$i$，它贡献$x$到从以下位置开始的每个后缀$i$，但前提是稍后没有出现更大的值。 

约束条件$k \le 360$是关键信号。 虽然$n$可以达到$10^5$，我们分配的总“资源”很小。 任何依赖于的解决方案$k$状态是合理的，而任何二次方$n$不是。 

一个天真的尝试会尝试所有的分配$b_i$，但即使独立选择值也已经大致给出$(k+1)^n$的可能性，这是完全不可行的。 即使是贪婪的选择也会失败，因为尽早放置一个大值可以改善许多前缀，但会消耗稍后可能会更好花的预算。 

早期大数据时会出现微妙的边缘情况$a_i$诱惑我们分配大的$b_i$立即地。 例如，如果$a = [100, 1, 1]$和$k=2$，选择$b_1=2$在本地看起来是最优的，但最好的策略可能是根据后面的位置进行不同的分布，因为每个大值对前缀和都有长期的乘法效应。 

另一个边缘情况是当很多$a_i = 0$。 这些位置在排序中仍然很重要，因为它们延长了所选最大值继续贡献的时间，即使它们不能直接增加最大值。 

## 方法

 关键的观察是，最终得分仅取决于成为新前缀最大值的值以及引入它们的位置。 一旦达到新的最大值$x$出现在位置$i$，后面的每个前缀至少贡献$x$，直到出现更大的值。 

所以问题就变成了：随着时间的推移，我们在最大值中选择几次“跳跃”，其中每次跳跃都有成本（价值本身贡献于总预算）和收益（它在一段时间内做出贡献）。 

这表明对所使用的牌的数量和我们处理的位置的数量进行动态编程。 然而，我们实际上并不需要完整的序列维度。 我们只需要知道到目前为止我们已经使用了多少张卡以及在处理前缀时我们可以积累多少贡献。 

一个有用的重新解释是按顺序处理位置并根据我们使用的卡牌数量维持 DP。 在每个位置$i$，我们决定处理后什么值成为当前最大值$i$。 由于最大值不会随时间减少，因此每个状态对应于选定的当前最大值$x$，并且我们分配增量$x$跨越未来的前缀。 

关键的结构是将当前最大值从$x$到$x + d$在位置$i$成本$d$卡并增加所有剩余后缀前缀的贡献。 因为$k$很小，我们可以将 DP 状态视为“使用了多少张卡”和“迄今为止最大级别的最佳总贡献”。 

我们迭代位置，对于每个位置，我们允许转换，要么保持当前最大值不变，要么将其增加到$a_i$，支付费用差额。 每次增加都会线性地改变所有未来的贡献，因此我们可以维持 DP，其中每个状态跟踪最佳可实现的总数（如果我们准确地使用了$c$到目前为止的卡数，当前的最大值是$x$。 

这导致了标准的背包式 DP$k$，但由于稍后扩展最大值有助于产生更多后缀这一事实而丰富。 我们按顺序处理位置并向后更新 DP$k$，确保我们不会多次重复使用同一个位置。

 ## 算法演练

 我们定义一个 DP 数组，其中`dp[c]`表示我们在处理朋友的某些前缀后能够获得的最大总幸福感，准确地使用了`c`卡总数。 

我们还坚持这样的想法：扩展所选值有助于未来的前缀。 我们没有明确地跟踪前缀最大值，而是结合了这样一个事实：如果我们分配一个值`v`在位置`i`，它贡献`v`致所有后缀贡献，起始于`i`。 

1. 初始化`dp[0] = 0`和所有其他州的数字都是非常负的。 这代表我们最初没有使用任何卡，也没有贡献。 
2. 从左到右处理好友。 在朋友处`i`，我们根据是否给这个朋友分配卡片来考虑更新DP。 
3. 对于每个可能使用的总电流`c`，我们考虑分配一个值`x`定位`i`， 在哪里$0 \le x \le a_i$和$c + x \le k$。 分配的贡献`x`在位置`i`是：

 当前前缀贡献加`x * (n - i + 1)`因为一旦出现新的最大值`x`引入后，它对于所有剩余的后缀前缀仍然有效。 

这种视角将问题转化为每个位置的加权背包选择。 
4.我们更新一个新的DP数组`ndp`通过尝试所有有效的转换`dp[c]`到`ndp[c + x]`。 
5. 处理完所有值后`x`对于每个`i`，我们替换`dp`和`ndp`。 
6. 最后，答案是最大的`dp[c]`为了`c <= k`。 

关键是每张卡牌的贡献取决于其保持最大值的时间长短，而 DP 确保我们在各个位置上以最佳方式分配每个单位。 

### 为什么它有效

 不变量是在处理完第一个之后`i`职位，`dp[c]`准确地存储可实现的最佳总体幸福感`c`卡片，仅考虑达到索引的好友`i`。 每次过渡都保留了可行性，因为我们永远不会超出每个朋友的容量或全球预算。 

正确性源自以下事实：每个有效的构造$b$可以分解为独立的每个位置贡献，并且 DP 枚举所有此类分布而无需重复。 前缀最大行为由每个指定值的线性持久性捕获，因此未来的决策不会使早期的贡献无效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        NEG = -10**18
        dp = [NEG] * (k + 1)
        dp[0] = 0

        for i in range(n):
            ndp = [NEG] * (k + 1)

            for c in range(k + 1):
                if dp[c] < 0:
                    continue
                # option: assign x cards to friend i
                max_x = min(a[i], k - c)
                for x in range(max_x + 1):
                    nc = c + x
                    # contribution: x persists from position i onward
                    gain = dp[c] + x * (n - i)
                    if gain > ndp[nc]:
                        ndp[nc] = gain

            dp = ndp

        print(max(dp))

if __name__ == "__main__":
    solve()
```该实现在已用卡总数上保持背包式 DP。 内部循环枚举我们给当前朋友的卡片数量，同时考虑每个朋友的限制和剩余预算。 

表达式`x * (n - i)`如果我们将贡献解释为从当前位置开始累积，则捕获有多少后缀前缀受到影响。 DP 更新是在一个新的数组中完成的，以避免多次重复使用同一个友元。 

一个微妙的细节是用较大的负值初始化无法到达的状态。 这可以防止无效的转换传播为看起来有效的结果。 另外，迭代`c`向上或向下在这里并不重要，因为我们使用单独的`ndp`。

 ## 边缘情况

 一个关键的边缘情况是当所有$a_i = 0$。 DP 永远不会脱离零牌，因此答案始终保持零。 任何假设至少有一次正分配的贪婪尝试都会错误地多计贡献。 

另一种情况是当一个大的$a_i$出现在最后。 该算法正确地将支出预算推迟到最终位置，因为这些位置可以最大化持久性。 天真的从左到右的贪婪分配会错误地过早支出并失去长期贡献。 

第三种情况是当$k$相对于个体而言较大$a_i$但总体较小。 DP 确保跨多个位置的部分分配，并且没有任何一步会强制充分利用容量，从而保持最佳的拆分行为。
