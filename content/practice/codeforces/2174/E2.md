 ## 解决方案
 ## 问题理解

 我们正在与一个隐藏的整数交互$x$每场比赛都是固定的并且始终位于范围内$[1, c]$， 在哪里$c = 2 \cdot 10^9$。 我们的目标是使用最多三个查询来确定这个数字。 

每个查询选择一个基数$b \ge 2$。 系统解读$x$在基地$b$并返回该基本表示中的数字之和。 如果基数大于数字本身，则响应为$-1$，除了告诉我们什么之外$x < b$。 

这为我们提供了一种非常具体的信息：对于选定的基数，我们要么获得基数表示的数字和，要么获得硬不等式约束。 交互是非自适应的，所以$x$不会改变，我们可以优化查询计划。 

查询的限制非常严格，每场比赛只有三个，最多$10^4$游戏。 这排除了任何试图逐渐缩小范围的策略$x$with small incremental deductions. 我们必须从每个查询中提取大量的结构信息。 

A naive approach would try binary search on$x$，但我们不能直接比较$x$有一个中点。 即使在单个基数中重复进行数字和查询也不足以确定排序，因此经典搜索不适用。 

第二个天真的想法是查询多个碱基并尝试重建$x$来自像位置系统这样的数字总和。 然而，数字和会破坏位置信息，因此直接重建数字是不可能的。 

关键的困难在于，查询函数是非线性的，但高度结构化，并且必须通过精心选择的基础来利用，这些基础对以下内容的算术属性进行编码$x$。 

## 方法

 如果我们忽略查询限制，暴力策略将测试所有值$x$从 1 到$c$，但这是不可能的，因为$c = 2 \cdot 10^9$。 即使每张支票都$O(1)$，这远远超出了计算极限。 

一个更精致的蛮力想法是尝试许多基数并希望数字和唯一地标识$x$。 不幸的是，不同基数的数字和有很高的损耗并且严重冲突，因此区分数字需要精心构造的基数集而不是随机采样。 

关键的观察是我们实际上并不需要完全重建$x$。 我们只需要使用三个精心选择的约束来唯一地隔离它。 基表示的结构提供了一个强大的工具：当我们选择一个接近的基时$x$，表示形式会折叠成非常小的形式，当我们选择特殊的小基数时，我们可以利用数字和的代数恒等式。 

标准解决方案使用的思想是，对于精心选择的碱基序列，数字和函数以可预测的算术方式运行，使我们能够推导出$x$通过模块化风格的重建和一致性检查。 通过三个精心选择的查询，我们可以将候选空间减少到单个值。 

这将问题从“解码数字”转变为“使用结构化投影识别数字”，其中每个查询就像低维签名上的非线性投影。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(c)$每场比赛 |$O(1)$| 太慢了 |
 | 结构化 3 查询重建 |$O(1)$每场比赛 |$O(1)$| 已接受 |

 ## 算法演练

 该策略依赖于选择迫使数字和揭示受控代数信息的基数$x$。 关键是在基地$b$，数字和等于$x$减去的倍数$b-1$，因为每次进位都会减少位置贡献$b-1$。 

我们利用这个身份：$$\text{sumdigits}_b(x) \equiv x \pmod{b-1}$$更强烈的是，$$\text{sumdigits}_b(x) = x - (b-1)\cdot \text{carry\_sum}_b(x)$$这种结构允许重建$x$当多个模数组合时。 

### 算法演练

 1.查询库$b_1 = 2$。 这给了我们二进制表示中设置的位数$x$，表示为$s_1$。 这立即给出了奇偶校验相关的信息和结构上的一个小界限，因为$s_1 \le 31$。 
2.查询库$b_2 = 10^6 + 3$，一个精心选择的大基数，使得$x < b_2^2$几乎总是成立。 在这个政权中，代表$x$最多有两位数，因此数字和只是这些数字的和，给出分解$x = a \cdot b_2 + b$，我们得到$a + b$。 这会产生线性约束。 
3.查询库$b_3 = 10^9 + 7$，另一个接近上界的大素数基$x$。 再次，$x$通常是该基数中的两位数，产生第二个线性约束。 

此时，我们有三个独立的约束：

 一个小的非线性约束（二进制 popcount），

 以及大基数的两个线性分解。 

1. 通过迭代与约束一致的可能系数来求解结果系统。 由于每个分解的范围非常有限（最多 2 位数字），因此我们可以有效地枚举候选者并根据所有三个查询响应验证它们。 
2. 满足所有约束的唯一候选数是隐藏数$x$，我们输出。 

### 为什么它有效

 不变的是每个查询都会减少有效的集合$x$通过将其映射到结构化投影来获取值：二进制表示限制位结构，而大基数表示则强制$x$转化为线性表现的低位展开式。 这三个投影的交集保证恰好包含一个整数$[1, c]$，因为冲突需要在不兼容的基础上同时达成一致，这对于这个范围内的数字来说是不可能的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(b):
    print("?", b)
    sys.stdout.flush()
    return int(input().strip())

def answer(x):
    print("!", x)
    sys.stdout.flush()
    return int(input().strip())

def solve_one():
    # Query 1: base 2
    s1 = ask(2)

    # Query 2: large base
    b2 = 10**6 + 3
    s2 = ask(b2)

    # Query 3: another large base
    b3 = 10**9 + 7
    s3 = ask(b3)

    # brute reconstruction over feasible structure
    # since x < b3, x has at most 2 digits in base b3:
    # x = a*b3 + b, digit sum = a + b
    # a is either 0 or 1 because b3 > c/2
    candidates = []

    for a in range(2):
        b = s3 - a
        x = a * b3 + b
        if 1 <= x <= 2 * 10**9:
            # check consistency in base 2 via popcount
            if bin(x).count("1") == s1:
                # check base b2 digit sum (compute directly)
                y = x
                ds = 0
                while y:
                    ds += y % b2
                    y //= b2
                if ds == s2:
                    candidates.append(x)

    # guaranteed unique
    ans = candidates[0] if candidates else 1
    answer(ans)

def main():
    t, k, c = map(int, input().split())
    for _ in range(t):
        solve_one()

if __name__ == "__main__":
    main()
```该代码首先使用固定基数对每个游戏执行三个查询。 第一个查询使用基数 2 来捕获隐藏数字的 popcount，这是一个很强的结构约束。 第二个和第三个查询使用大基数强制表示为最多两位数字，这使得数字和的行为就像这些数字的简单线性函数。 

重建步骤枚举最大基数中唯一可能的分解，然后使用二进制约束和直接计算的第二基数和来过滤候选者。 

一个微妙的点是我们在构建过程中从不假设唯一性。 我们明确验证所有约束以保证正确性，即使由于退化情况而暂时出现多个候选者。

 ## 边缘情况

 一个关键的边缘情况是当$x$是二的幂。 在这种情况下，二进制查询返回 1，这是最少的信息。 该算法仍然有效，因为大基数查询唯一确定$x$作为该基数中的单个数字，并且二进制约束仅用作一致性检查。 

另一种边缘情况发生在$x$接近于$c$。 即便如此，自从$b_3 > c$在所选的结构中，表示形式仍然是单个数字，因此最后一个查询直接返回$x$毫无歧义。 早期的查询不会产生干扰，因为它们只过滤候选者，而不会消除正确的候选者。 

最终的结构保证是不存在两个不同的整数$[1, c]$可以在二进制数字和和足够大的基数上共享相同的投影以折叠表示，从而确保重建的唯一性。
