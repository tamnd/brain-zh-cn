 ## 解决方案
 ## 问题理解

 我们得到一个等于零的起始值和一个以二进制形式写入的目标数。 我们希望使用两个算术运算将初始零转换为该目标：我们可以将当前值加一，或者将其乘以二。 

每个操作都与物理机器绑定。 加法机在仓库的左侧，乘法机在右侧。 从入口步行到左侧机器需要花费`p`, 正确的机器成本`q`，以及在机器之间直接移动的成本`p + q`。 完成所有操作后，我们必须返回入口处。 

我们每次执行一个操作，首先要到对应的机器，支付它的操作费用（`a`对于+1，`b`×2），并支付从我们当前位置到达它所需的任何步行成本。 

目标的二进制表示形式固定了算术运算的顺序。 从最高有效位到最低有效位读取位，我们有效地构建数字：移动到下一位时左移（乘以 2），并在设置该位时加 1。 

核心困难在于，虽然算术运算的顺序是由二进制结构固定的，但我们可以自由决定在哪里执行每个运算，并且在机器之间移动的成本很高。 

输入大小高达 100000 位，这排除了任何试图显式模拟每个可能的路由选择的方法。 任何按操作分支或尝试重复重新计算机器状态之间的最短路径的解决方案都将超出时间限制。 我们需要一个线性结构，其中每个位贡献恒定的工作量。 

当目标为零时，会出现微妙的极端情况。 在这种情况下，不需要任何操作，我们只返回零成本。 另一种重要的情况是，当仅使用一种机器类型处理所有位时，这可能会诱使贪婪的解决方案停留在一个位置，但这并不总是最佳的，因为移动成本可能会主导操作节省。 

## 方法

 直接模拟将尝试在构建二进制数的每一步中决定是走向加法机还是乘法机。 这导致了指数数量的可能的运动模式。 即使修剪也无济于事，因为决策的成本取决于未来的操作，特别是当长时间的乘法运算之后偶尔进行加法时。 

关键的观察是该过程的算术部分是由二进制表示固定的。 对于有长度的数字`L`，我们总是执行`L-1`乘法，并且对于每个`1`在第一个之后，我们执行加法。 唯一的自由在于哪台机器执行每个操作。 

这将问题转化为非常小的状态空间上的最短路径。 在任何时候，唯一相关的信息就是我们当前所在的位置：入口处、加法机处或乘法机处。 我们如何到达那里的历史并不重要，因为未来的成本仅取决于下一个所需的机器和当前的位置。 

因此，我们对二进制字符串引发的操作序列计算动态规划。 每个步骤都会更新执行前缀操作后到达每个位置的最小成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有机器路线进行暴力破解 | 指数| 指数| 太慢了|
 | DP超操作指数及位置| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将数字的构造视为从二进制字符串派生的固定操作序列。 

1. 如果目标是`"0"`，我们立即返回 0，因为不需要任何操作，并且我们已经得到了正确的值。 
2.我们定义三个可能的位置：入口、加法机、乘法机。 我们维护一个 DP 数组，存储当前站在每个位置时完成已处理的操作前缀的最小成本。 
3. 在进行任何操作之前，我们从入口处开始，成本为0。 
4. 我们单独处理第一位。 由于数字是正数，因此第一位始终是`1`。 我们必须执行一个`+1`手术。 从当前的任何位置，我们考虑移动到加法机，支付从该位置出发的旅行费用，然后支付`a`进行操作。 这将初始化 DP 以进行第一步。 
5. 对于每个后续位，我们首先执行乘以 2，这始终对应于前往乘法机，支付从前一个位置加上的行程成本`b`。 
6. 如果当前位是`1`，我们在乘法步骤之后另外执行加法运算。 这需要移动到加法机并付款`a`。 通过按顺序考虑该位的两个操作来更新 DP。 
7. 处理完所有位后，我们可以在三个位置中的任何一个结束，但必须返回入口。 因此，我们取所有最终 DP 状态的最小值加上走回入口的成本。 

关键的结构是每个位都贡献一个固定的小操作序列，并且每个操作仅取决于前一个位置和下一个所需的机器。 

### 为什么它有效

 在该过程中的任何一点，影响未来成本的唯一信息是当前位置和二进制结构中的位置。 处理相同前缀后在同一台机器上结束的任何两个执行历史都是等效的，因为所有未来的操作都会看到相同的起始状态。 这建立了一个最优的子结构：达到某个状态的最佳方式与我们如何到达那里无关，从而允许 DP 安全地丢弃次优历史。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

def cost_move(frm, to, p, q):
    if frm == to:
        return 0
    if frm == 0:  # entrance
        return p if to == 1 else q
    if to == 0:
        return p if frm == 1 else q
    # between machines
    return p + q

def solve():
    a, b = map(int, input().split())
    p, q = map(int, input().split())
    s = input().strip()

    if s == "0":
        print(0)
        return

    # states: 0 = entrance, 1 = add machine, 2 = mul machine
    dp = [INF, INF, INF]

    # first bit must be '1' in valid input
    ndp = [INF, INF, INF]
    for frm in range(3):
        ndp[1] = min(ndp[1], dp[frm] + cost_move(frm, 1, p, q) + a)
    dp = ndp

    for ch in s[1:]:
        # multiplication step (always)
        ndp = [INF, INF, INF]
        for frm in range(3):
            ndp[2] = min(ndp[2], dp[frm] + cost_move(frm, 2, p, q) + b)
        dp = ndp

        if ch == '1':
            ndp = [INF, INF, INF]
            for frm in range(3):
                ndp[1] = min(ndp[1], dp[frm] + cost_move(frm, 1, p, q) + a)
            dp = ndp

    ans = min(dp[i] + cost_move(i, 0, p, q) for i in range(3))
    print(ans)

if __name__ == "__main__":
    solve()
```DP 数组在处理二进制字符串的每个前缀后跟踪最已知的成本。 每次更新都会覆盖以前的状态，因为只有最后一个位置重要，而不是完整路径。 这`cost_move`函数对所有行走规则进行编码，包括通过入口成本结构在机器之间直接转换。 

一个常见的实现错误是忘记在乘法步骤之后我们必须留在乘法机上，除非我们明确地再次移动进行加法。 另一个常见错误是忽略最终返回入口成本，该成本与最后一次操作无关，但必须在最后包含一次。

 ## 边缘情况

 对于输入`s = "0"`，算法立即返回0并跳过所有DP逻辑。 这是正确的，因为不需要算术运算并且移动成本无关。 

对于像这样的单位字符串`"1"`，仅执行一次加法运算。 DP评估是否值得从入口直接前往加法机或考虑中间状态，但由于没有先验结构，结果减少为单次移动加上操作成本，匹配最优路径。 

对于交替模式，例如`"1010..."`，DP 不断比较留在一台机器附近并支付重复移动成本是否比每次操作切换更便宜。 状态压缩确保考虑所有此类权衡，而无需显式枚举路径。
