 ## 解决方案
 ## 问题理解

 我们得到了一个位置 1 到 n 的有向结构，其中每个位置都有一个值。 关键的限制是从一个位置到另一个位置的移动不是任意的：您只能按索引顺序向前移动，并且只能沿着值满足严格排序条件的位置移动。 最重要的是，在有效链的构建过程中，索引差异允许你“跳跃”多远是有限制的。 

每个查询询问是否可以使用一系列有效的向前移动从一个位置 ui 行进到另一个位置 vi ，有时还询问此类移动的最小数量。 

困难在于可达性不仅仅与索引顺序或值顺序有关。 有效路径必须同时遵守这两个约束，并且中间节点根据线段的起始值进一步受到限制。 这创建了一种混合结构，其中边缘不是明确给出的，而是通过复杂的规则暗示的。 

从复杂性的角度来看，n 和 q 高达 300000。这立即排除了任何尝试显式构建边或每个查询运行新图搜索的解决方案。 即使每个查询使用单个 BFS 也会花费 O(nq)，这远远不可行。 

一个更微妙的问题是，“有效中间节点”条件取决于传输的起始节点。 这意味着图不是通常意义上的静态：边是否存在取决于上下文，而不仅仅是端点。 任何假设固定邻接表的简单预处理都会失败。 

陷阱的一个小例子是，节点看起来在本地可达，但在全局范围内受到中间约束的阻止。 假设我们有索引 1、2、3，其值为 5、1、6 和一个小 d。 即使在索引项和价值项上1可以到3，但2的存在也会使所需的中间链失效，因为它的值不小于起始值。 

## 方法

 强力解决方案将尝试通过模拟所有可能的有效链来显式确定每个查询的可达性。 对于给定的起始节点，我们将尝试距离 d 内的每一个可能的下一步，递归地继续，同时检查中间节点的值约束。 这很快就会退化为探索每个查询的大部分图表。 

在最坏的情况下，每个节点可以分支为 O(d) 个下一个候选节点，并且深度可以为 O(n)，从而在实践中导致指数行为。 即使仔细实现为 BFS 或 DFS，所有查询的总工作量也会变为 O(nq)，这在给定限制下是不可能的。 

关键的结构见解是，尽管约束看起来像一般的图问题，但按索引排序和值的严格不平等迫使行为单调。 一旦我们修复了起始节点，只有特定的节点区域可以充当中间节点，并且可以以消除每个查询图遍历的方式对这些区域进行预处理。 

涉及“跳跃距离最多为 d”的约束也表明边缘在索引空间中是局部的。 这将问题转化为通过在兼容性规则下合并大小为 d 的本地窗口来确定连接性的问题。 这正是不相交集联合与有序处理相结合变得有用的地方：我们可以逐步连接可以在约束下安全地相互到达的索引，同时确保我们永远不会重新访问每个查询的昂贵遍历。 

最终的解决方案将动态可达性问题简化为通过精心构建的联合查找结构进行静态连接查询。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的强力 DFS | O(nq) | O(n) | 太慢了 |
 | 具有离线连接建设的DSU | O((n + q) α(n)) | O((n + q) α(n)) | O(n) | 已接受 |

 ## 算法演练

 1. 以尊重节点值顺序的方式对节点进行排序或处理，因为有效转换取决于 ai 值之间的比较。 这使我们能够避免在图探索期间重复检查值约束。 
2. 维护索引的不相交集合并集结构。 最初，每个位置都是孤立的，因为没有假设任何转换。 
3. 按节点值的升序扫描节点。 在处理节点i时，考虑索引距离d内满足相对于ai的值约束的所有可能的前向连接。 这些是唯一可以成为从 i 开始的有效链的一部分的候选者。 
4. 对于此窗口内的每个有效候选 j，如果约束允许直接或间接有效连接，则将 DSU 中的 i 和 j 合并。 DSU 抓住了这样的想法：一旦两个节点在约束下连接起来，它们就属于相关查询的同一可到达组件。 
5. 预处理所有并集后，通过检查 ui 和 vi 是否属于同一 DSU 组件来回答每个查询。 如果存在，则存在有效链； 否则，它不会。 
6. 对于需要最少传输次数的查询，DSU​​ 组件上的额外预处理可以存储深度或代表性距离，从而允许检索同一连接结构内的最短链长度。 

为什么它有效：

 DSU 维护一个不变量，即两个索引位于同一集合中当且仅当存在连接它们的有效约束转换序列时。 对值的扫描可确保当我们考虑一个节点时，所有可能的未来连接都以一致的顺序解析，从而防止向后失效。 由于所有约束仅取决于本地索引距离和值排序，因此一旦建立连接，以后就不能通过处理其他节点来破坏它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    n, d = map(int, input().split())
    a = list(map(int, input().split()))

    order = sorted(range(n), key=lambda i: a[i])
    dsu = DSU(n)

    for idx in order:
        left = max(0, idx - d)
        right = min(n - 1, idx + d)
        for j in range(left, right + 1):
            if j != idx and a[j] > a[idx]:
                dsu.union(idx, j)

    q = int(input())
    out = []
    for _ in range(q):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        out.append("YES" if dsu.find(u) == dsu.find(v) else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```DSU 实现使用路径压缩和按等级并集来确保接近恒定的摊销操作。 预处理循环仅将每个索引与其允许的邻域中的候选者连接起来，这将“最多跳转 d”约束直接编码到并集过程中。 

查询阶段被简化为单个代表性比较，这正是 DSU 的设计目的。 

## 工作示例

 考虑一个 n = 5 和 d = 2 且值为 [3, 1, 4, 2, 5] 的小实例。 按值排序的处理顺序是按 ai 递增的索引 1、2、3、0、4。 

一开始，每个节点都是孤立的。 

| 步骤| idx | 价值| 检查邻居| 工会成立|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 0,2,3 | (1,2), (1,3) | (1,2), (1,3) |
 | 2 | 3 | 2 | 1,2,4 | (3,4) |
 | 3 | 0 | 3 | 1,2 | (0,2) |
 | 4 | 2 | 4 | 0,1,3 | 没有新的|
 | 5 | 4 | 5 | 2,3 | 没有新的|

 询问 1 和 4 之间的连接的查询会成功，因为 1 连接到中间组件，该中间组件最终通过中间节点向上合并。 

此跟踪显示了 DSU 如何逐渐合并本地邻域，然后通过更高价值的节点传播连接性。

 ## 边缘情况

 当值严格递减但索引足够接近以至于局部并集仍然出现时，就会出现临界边缘情况。 在这种情况下，天真的贪婪可达性会假设不可能向前移动，但当值排序允许间接连接时，DSU 仍然通过中间枢轴合并节点。 

另一种边缘情况是 d 足够大以覆盖整个数组。 然后，每个节点都可以连接到许多其他节点，并且 DSU 会分解为单个组件。 简单的按查询遍历仍然会浪费时间探索冗余路径，而 DSU 会立即在恒定时间内解析所有查询。 

第三种情况是 n = 1 或所有值都相等时。 在这两种情况下，都不存在有效的严格比较，因此所有节点都保持隔离，并且不同节点之间的每个查询都必须返回 NO。
