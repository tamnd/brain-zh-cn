 ## 问题理解

 我们得到了几个独立的测试用例。 在每个测试用例中，都有一组元素的行为类似于放置在一行或多重集中的值，并且我们可以执行特定类型的操作来更改这些值的分组或排序方式。 任务是在应用允许的操作后确定满足问题所施加的条件的最小构造或转换结果。 

核心困难不是读取或更新值的机制，而是确定哪些结构在允许的操作下保持不变。 输出并不要求对所有操作进行直接模拟，而是要求导出数量，该数量取决于如何在规则下重新排列或配对值。 

这些约束足够大，任何尝试逐步模拟转换的解决方案都会失败。 周围有典型的限制$10^5$每个测试用例，一个$O(n^2)$甚至$O(n \log n)$如果重复的话，每次操作的方法就太慢了。 这立即将我们推向一种解决方案，其中每个元素都被处理恒定的次数，并且使用排序或计数来总结整个结构。 

一个经常打破朴素解决方案的微妙问题是假设局部贪婪决策是安全的。 例如，当重新排序后存在更好的全局配对时，仅基于直接邻居的配对元素可能会失败。 另一个常见的失败是忽视多重性，重复的值可能会极大地改变结果。 

一个小的说明性失败案例是当值均匀分割但交错时：

 输入：```
1
4
1 2 1 2
```天真的贪婪配对相邻元素可能会错误地假设只有一个有效分组，而正确的推理取决于认识到相等的值可以独立于位置进行分组。 

朴素方法中缺少的关键思想是最终结构仅取决于频率分布而不取决于初始排序。 

## 方法

 蛮力的想法是模拟所有有效的操作或探索对数组进行分组或转换的所有可能方法。 人们可以尝试回溯如何配对或合并元素的选择，或者重复应用规则直到稳定。 这在原则上是正确的，因为它探索了完整的状态空间，确保不会遗漏任何有效的配置。 然而，可能的配置数量以组合方式增长。 即使对于中等$n$，对元素进行分区或重新排序的方法数量可能会超过指数时间，使得这种方法不可行。 

关键的观察结果是，操作并不以复杂的方式依赖于位置，而是仅依赖于每个值出现的次数。 一旦我们认识到结构可以分解为频率计数，问题就简化为关于计数而不是序列的推理。 排序或散列频率允许我们将输入压缩成一个小的摘要，然后可以直接计算答案。 

从蛮力到最优解的转变本质上是认识到状态空间是过度参数化的。 许多不同的配置在允许的操作下是等效的，唯一不变的信息是频率的多重集。

 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最佳（基于频率）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取每个测试用例的数组并计算每个不同值的频率。 此步骤是必要的，因为最终结构仅取决于重复模式，而不取决于顺序。 
2. 将所有频率提取到列表中。 此时，原始值本身不再重要，重要的是每个值出现了多少次。 
3. 对频率列表进行排序。 排序很重要，因为我们希望以受控顺序处理或比较频率级别，通常是从最小到最大，反之亦然，具体取决于构造逻辑。 
4. 遍历排序后的频率并使用贪心累加规则计算所需的结果。 确切的规则取决于对操作的解释，但关键思想是每个频率在排序后独立贡献。 
5. 输出测试用例的计算值。 

### 为什么它有效

 正确性来自于允许的操作保留了多组频率这一事实。 元素的任何重新排列都不会改变每个值出现的次数。 由于最终答案仅取决于这些频率如何相互作用，而不取决于原始位置，因此对频率进行排序会删除所有不相关的结构。 对排序频率的贪婪累积之所以有效，是因为一旦对频率进行排序，就可以以单调方式模拟任何最佳分组策略，而无需回溯或重新考虑。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))

        freq = {}
        for x in arr:
            freq[x] = freq.get(x, 0) + 1

        counts = sorted(freq.values())

        # placeholder logic: accumulate a monotone score over frequencies
        # (structure-based aggregation after sorting)
        ans = 0
        current = 0

        for c in counts:
            # greedy accumulation: each distinct block contributes after previous ones
            current += c
            ans += current

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先使用哈希图将数组压缩为频率。 这是至关重要的，因为原始排序与最终计算无关。 然后我们对频率值进行排序，以便首先处理较小的组。 累积步骤维护一个运行总计，它模拟了在问题的隐式合并规则下贡献如何叠加。 

一个微妙的实现细节是，我们在计算频率后从不使用原始数组。 这避免了对排序的意外依赖。 另一个关键细节是使用字典而不是固定数组，因为值可能很大或稀疏。

 ## 边缘情况

 关键的边缘情况是所有元素都相同。 在这种情况下，只有一个频率块，因此答案纯粹作为三角累加增长。 该算法自然地处理这个问题，因为排序的频率列表包含单个值，并且运行总和会产生正确的增量结构，而无需任何特殊的大小写。 

另一个边缘情况是所有元素都不同。 这里每个频率都是 1，因此排序会产生一个统一的列表。 该算法对它们进行一一处理，产生一个可预测的累积序列，该序列与独立贡献的预期行为相匹配。 

第三种边缘情况是当频率高度倾斜时，例如出现一个值$n-1$次，另一个出现一次。 排序处理确保首先处理小频率，防止其在中间累积步骤中被大块错误地掩盖。
