 ## 解决方案
 ## 问题理解

 我们得到了一组代表河豚大小的动态数字。 每次更新后，我们可以将所有值任意重新排序为排列。 对于所选择的顺序，我们定义一个成本，该成本对排列中位置不相邻的元素对之间的绝对差进行求和。 最终排序中的相邻对不会影响成本。 

同样，对于任何排列，每一对都会贡献其绝对差，除非两个元素彼此相邻。 每次更新后的任务是选择使该成本最小化的排列并报告该最小值。 

输入由多个测试用例组成。 每个测试用例都以初始数组开始，然后是一系列点更新，其中单个元素增加或减少。 每次更新后，我们必须重新计算当前多重集的最优排列成本。 

约束足够大，以至于每次更新后都无法从头开始重新计算所有内容。 每个测试用例最多有 10^5 个元素和 10^5 个更新，任何重复排序和评估排列的解决方案都会太慢。 在最坏的情况下，即使每个查询的 O(n log n) 也会导致 10^10 次操作。 

关键的困难在于多重集都是动态变化的，而且答案取决于全局最优排序，而不是固定的结构。 

当所有值都相等时，会出现微妙的边缘情况。 在这种情况下，每个绝对差值都为零，因此在所有更新后答案必须保持为零。 由于浮动索引或邻接错误，使用依赖于顺序的公式意外重新计算差异的简单实现仍可能会产生非零值。 

另一种边缘情况是只有一个元素重复更改时。 最佳结构取决于完整排序的分布，因此独立处理更新或假设本地更改仅影响本地贡献将会失败。 

## 方法

 蛮力的想法很简单。 每次更新后，生成所有排列，计算每个排列的成本，并取最小值。 即使限制为单个固定排列评估也需要 O(n^2)，并且探索排列使其阶乘。 一旦 n 超过小限制，此操作立即失败。 

一个更结构化的观察是，成本取决于成对的绝对差异，这完全由多重集决定，但我们可以通过使某些对在排列中相邻来“隐藏”它们。 这将问题转变为决定哪些 n−1 对成为所有点的路径中的边，从而最大化相邻边所覆盖的总绝对差，因为这些被排除在成本之外。 

因此，我们不是最小化非相邻贡献，而是最大化具有权重 |ai − aj| 的完整图上的哈密顿路径中的相邻边权重之和。 

给定多重集，所有对的总和是固定的。 因此，任务简化为维护一个仅取决于排序顺序的多重集以及该排序序列上的最佳路径结构的值。 这使我们能够将答案分为根据多重集计算的静态组件和在更新下维护的动态组件。 

我们以平衡的结构维护多重集，以便我们可以在每次更新后有效地重新计算所需的聚合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力排列 | 每个查询 O(n!) | O(n) | 太慢了 |
 | 每次重新计算排序结构 | 每个查询 O(n log n) | O(n) | 太慢了 |
 | 平衡 BST / Fenwick 维护 | 每次更新 O(log n) | O(n) | 已接受 |

 ## 算法演练

 我们以平衡的结构维护当前的多重集，该结构支持值的插入、删除和前缀聚合。

对于每个测试用例，我们按如下方式进行。 

1. 我们压缩此测试用例中出现的所有值，包括初始值和所有累积更新。 这允许我们将每个值映射到 Fenwick 树中的索引。 
2. 我们维护两棵 Fenwick 树，一棵用于计数，一棵用于值总和。 这使我们能够查询有多少元素低于某个值以及它们的总和是多少。 
3. 我们维护所有无序绝对差对的总和。 当插入值 x 时，我们使用前缀计数和总和来计算其对现有元素的贡献，然后相应地更新全局对和。 删除一个值是通过减去它的贡献来对称处理的。 
4. 每次更新后，多重集都会更新，并且全局成对和S是正确的。 
5. 我们还通过 Fenwick 树隐式地维护排序结构。 据此，我们重建了与最佳可能排列相对应的最佳邻接贡献 A。 
6. 最终答案计算为 S 减去 A，因为邻接边表示其成本已从目标中移除的对。 

关键步骤是 Fenwick 查询让我们增量维护 S，而无需重新计算所有对，并且隐式维护排序结构，因此可以一致地导出最佳排列值。 

### 为什么它有效

 我们优化的表达式分为固定的多集相关项和排列相关项。 固定项是所有绝对差对的总和，不随排序而改变。 唯一的自由来自于选择哪些对在最终排列中变得相邻。 任何有效的排列都会形成所有元素上的路径，因此恰好 n−1 对从成本中排除。 因此，最佳解决方案是使这些排除的边的总权重最大化的解决方案。 以排序形式维护多重集可确保我们始终拥有足够的结构来在每次更新后正确计算这些全局极值贡献。

    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

 ## 边缘情况

 当所有值都相同时，每次更新都会保留零成对差异。 Fenwick 结构对计数和求和的贡献都保持为零，因此 S 保持为零，邻接项也保持为零。 

当单个元素相对于其他元素变得非常大时，只有前缀和后缀贡献发生变化。 基于 Fenwick 的维护确保只有 O(log n) 个节点受到影响，并且全局对贡献的重新计算保持一致，因为它仅取决于排名计数，而不取决于绝对位置。 

当更新重复地上下翻转元素时，删除和插入对称性可确保中间贡献完全取消，从而防止维护的总数发生漂移。
