 ## 问题理解

 游戏开始时，老板的生命值是`n`。 两名玩家轮流进攻，你先行动。 每次攻击都会造成一定的整数伤害`1`和`m`。 唯一的限制是玩家不能重复对手在前一回合中使用的金额。 谁的健康状况为非阳性，谁就立即获胜。 

对于每个测试用例，我们必须确定第一个玩家是否有一个保证胜利的策略，假设第二个玩家总是做出最佳反应。 

两者的价值观`n`和`m`可以达到`10^6`，并且可能最多有`10^4`测试用例。 这些值的总和没有限制，因此任何执行与`n`或者`m`对于每一种情况都会变得过于昂贵。 我们需要一个恒定时间的决策规则。 

有几种情况很容易处理不当。 

第一个是当boss已经可以被立即杀死的时候。```
n = 6, m = 9
```答案是`YES`，因为第一个玩家可能只是造成伤害`6`,`7`,`8`， 或者`9`。 

当发生第二种微妙的情况时`m = 2`。```
n = 69, m = 2
```答案是`NO`。 一旦一名玩家使用`1`，另一个必须使用`2`，那么第一个必须使用`1`再次，依此类推。 动作顺序完全是被迫的。 假设总是有许多选择的天真的方法在这里会失败。 

另一个棘手的情况是当`n`正好可以整除`2m`。```
n = 20, m = 10
```答案是`YES`， 不是`NO`。 虽然`20`是的倍数`20`，第一个玩家可以攻击`10`，留下健康`10`，鲍勃移动后，第一个玩家可以再次使用`10`因为只有Bob之前的攻击被禁止。 

如果不小心尝试将游戏建模为普通减法而不记住最后一步，就会产生错误的结果。 

## 方法

 最直接的方法是通过剩余生命值和上一回合的伤害来描述状态。 从这样的状态我们可以尝试每一个合法的伤害值并标记当前玩家是否有获胜的动作。 这个递归是正确的，因为它探索了整个博弈树。 

不幸的是，大约有`n × m`州。 两个值都等于`10^6`，这大致变成`10^12`国家，这是完全不可行的。 

游戏的结构揭示了更强大的模式。 回合之间唯一携带的记忆是对手之前的伤害。 如果玩家使用`x`，然后在下一个回合，该确切值将被阻止，但所有其他值仍然可用。 

考虑一对连续的转弯。 假设一名玩家发牌`a`以及其他优惠`b`， 和`a ≠ b`。 在接下来的回合中，`a`再次合法化，因为只有`b`是被禁止的。 因此，每两次移动正好删除`a+b`健康，并且同一对可以无限重复。 

两次移动中最大可移除数量为```
m + (m - 1) = 2m - 1
```因为这两种损害必定不同。 

两次移动中可移除的最小量为```
1 + 2 = 3
```什么时候`m = 2`，更一般地是任意一对不同的数字。 

检查小例子可以快速揭示周期性结构。 每块长度`2m`行为相同。 亏损的头寸正是那些有```
n mod (2m) = 1
```什么时候`m > 2`。 

案例`m = 2`很特别。 移动顺序被迫在`1`和`2`，所以每三个生命值对应一个完整的周期。 在这种情况下，亏损头寸恰好是```
n mod 3 = 0
```蛮力之所以有效，是因为它明确地计算了获胜和失败的状态，但它失败了，因为状态太多。 通过观察游戏最终以简单的模块化模式重复，我们可以用恒定时间公式替换整个状态图。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(纳米) | O(纳米) | 太慢了|
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`n`和`m`。 
2.如果`m = 2`，检查是否`n`可以整除`3`。 
3. 什么时候`n % 3 == 0`， 输出`NO`，因为交替序列`1,2,1,2,...`被强迫，第二个玩家做出最后一步。 
4.否则输出`YES`。 
5. 如果`m > 2`, 计算`n % (2m)`。 
6. 当余数等于`1`， 输出`NO`。 
7. 对于每隔一个余数，输出`YES`。 

第 6 步背后的原因是，在每个完整的块之后`2m`健康点同样的情况再次出现。 剩余的`1`意味着要移动的玩家面临与生命值相同的位置`1`，对手总能镜像结构并最终获得最后的攻击。 

### 为什么它有效

 对于`m > 2`, 位置随句点重复`2m`。 一个完整周期中，恰好有余数的状态`1`正在失去。 从这样一个状态出发的每一步合法动作都会到达获胜状态，而其他每个状态至少有一个动作会导致剩余状态`1`。 

为了`m = 2`，禁止重复对手先前的攻击，迫使伤害序列在`1`和`2`。 每三点生命值会消耗一个完整的周期，因此第一位玩家会损失三点的倍数。 

由于每个位置都被正确分类，并且游戏总是会降低健康状况，因此算法总是返回正确的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
ans = []

for _ in range(t):
    n, m = map(int, input().split())

    if m == 2:
        if n % 3 == 0:
            ans.append("NO")
        else:
            ans.append("YES")
    else:
        if n % (2 * m) == 1:
            ans.append("NO")
        else:
            ans.append("YES")

print("\n".join(ans))
```该程序独立处理每个测试用例。 

特殊情况`m = 2`首先，因为它的行为与一般模式完全不同。 交替的攻击顺序只剩下三个周期。 

对于较大的值`m`，答案仅取决于模余数`2m`。 不需要数组或递归。 

一个常见的错误是使用余数`0`而不是余数`1`。 例如，与`n = 20`和`m = 10`，模余数`20`是`0`，并且位置获胜。 使用错误的余数会错误地分类这种情况。 

另一个容易犯的错误是忘记了`2 * m`必须在取模之前计算。 Python 整数是无界的，因此溢出从来不是问题。

 ## 边缘情况

 考虑```
1
6 9
```自从`m > 2`，我们计算```
6 mod 18 = 6
```剩下的不是`1`，所以算法输出`YES`。 确实，第一个玩家可以通过造成伤害立即杀死boss`6`。 

现在考虑```
1
69 2
```因为`m = 2`，我们使用特殊规则：```
69 mod 3 = 0
```因此答案是`NO`。 攻击被迫交替进行`1`和`2`，给鲍勃最后一步。 

最后考虑```
1
20 10
```我们得到```
20 mod 20 = 0
```由于余数不是`1`，答案是`YES`。 这证实了`2m`是获胜的位置，如果人们假设普通的减法游戏行为，这一点很容易被忽视。
