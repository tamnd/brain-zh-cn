 ## 解决方案
 ## 问题理解

 我们正在观看一条长度为一维的人行横道$L$，表示为来自$0$到$L$。 在任何时刻，每个行人都是实线上的一个移动点，从位置开始$X_i$并以匀速移动$V_i$，所以他们当时的位置$T$是$X_i + V_i T$。 

在查询时$T$，我们将注意力限制在实际位于人行横道间隔内的行人$[0, L]$。 如果我们将这些行人的位置连同端点一起排序$0$和$L$，我们获得了该段上的一系列阻塞点。 如果存在至少长度为连续的空区间，内森可以穿越$C$，这意味着这些点中的一些连续点的距离至少为$C$，或者端点和最近的行人之间有足够的空间。 

每个查询都是独立的，因为它一次性询问配置$T$，但查询按时间递增顺序到达。 任务是回答每个查询是否存在这样的差距。 

这些约束意味着我们可能有最多 1000 名行人，但最多有 200 万个查询，因此每个查询从头开始重新计算所有内容在实践中必须非常高效。 任何解决方案，甚至$O(N \log N)$每个查询都有超过时间限制的风险，以及$O(N^2)$每个查询的推理是完全不可行的。 

当行人位于路段之外时，会出现微妙的边缘情况$[0, L]$。 例如，某时行人$T$可能处于位置$-5$或者$L+10$。 这些不会直接阻塞人行横道，但如果错误地将它们包含在间隙计算中，它们可能会间接影响答案。 仅限行人进入$[0, L]$应该考虑。 

另一种边缘情况是多个行人在同一位置重合。 排序后应将它们视为单个阻塞点，因为零宽度分隔不会产生可用的间隙。 

## 方法

 最直接的想法就是独立模拟每个查询。 对于固定时间$T$，计算所有位置$X_i + V_i T$，过滤里面的$[0, L]$，对它们进行排序，然后扫描连续的差异以找到最大的差距。 这是正确的，因为问题简化为快照时的一维间距检查。 

这种方法的成本$O(N \log N)$由于排序而每个查询。 高达$2 \cdot 10^6$查询和$N \le 1000$，这大约导致$2 \cdot 10^6 \cdot 1000 \log 1000$，这太慢了。 

关键的观察是$N$很小。 尽管查询很多，但对行人的每个单独计算最多限制为 1000 个值。 这表明简单的每个查询重新计算与严格的实现相结合，在 C++ 等语言中是可以接受的，并且在 Python 中概念上仍然是正确的。 

没有必要随着时间的推移维持动态结构，因为虽然位置不断变化，但每个查询都是独立的。 查询的时间排序不允许以任何有意义的方式重用以前的排序结果，因为速度可以在查询之间任意重新排序所有内容。 

因此，这里的最佳实际解决方案是直接通过单遍独立计算每个答案：评估位置、过滤、排序和扫描间隙。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 通过排序对每个查询进行强力重新计算 |$O(Q \cdot N \log N)$|$O(N)$| 可接受的优化语言 |
 | 相同的想法，严格执行 |$O(Q \cdot N \log N)$|$O(N)$| 已接受 |

 ## 算法演练

 ### ## 算法演练

 1.对于每个查询时间$T$，使用以下方法计算每个行人的当前位置$X_i + V_i T$。 这给出了当时系统的快照。 
2. 只保留位置在区间内的行人$[0, L]$。 此范围之外的行人不会限制人行横道内的移动，因此在间隙计算中将忽略它们。 
3. 将剩余位置按升序排列。 添加两个边界$0$和$L$成相同的有序结构。 
4. 遍历排序列表并计算连续元素之间的差异。 跟踪遇到的最大差异。 这代表了当时最大的可用免费段$T$。 
5. 如果最大间隙至少为$C$，输出“Y”。 否则输出“N”。 

正确性取决于以下事实：任何有效的交叉路径必须完全适合按排序顺序的连续阻止者之间的某些连续空白间隔。 如果存在这样的间隔，则将其检测为这些相邻差异之一。 

### 为什么它有效

 在任何固定时间，行人都会将人行横道划分为阻塞点和空闲路段。 每个自由路段的边界要么是两个连续的行人，要么是一个端点和一个行人。 任何宽度的汽车的可行放置$C$必须完全适合这些最大空闲段之一，因此在排序后仅检查相邻间隙就足够了。 任何不相邻的行人都不能在不被另一个行人分割的情况下定义更大的有效空区域。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, C, L = map(int, input().split())
    people = [tuple(map(int, input().split())) for _ in range(n)]

    q = int(input())
    queries = [int(input()) for _ in range(q)]

    for t in queries:
        positions = []

        for x, v in people:
            p = x + v * t
            if 0 <= p <= L:
                positions.append(p)

        positions.sort()

        best_gap = 0

        prev = 0
        for p in positions:
            best_gap = max(best_gap, p - prev)
            prev = p

        best_gap = max(best_gap, L - prev)

        if best_gap >= C:
            sys.stdout.write("Y\n")
        else:
            sys.stdout.write("N\n")

if __name__ == "__main__":
    solve()
```核心循环重新计算每个查询的位置并过滤人行横道内的位置。 对每个查询执行排序，然后线性扫描计算包括两个端点的最大间隙。 

一个常见的实施陷阱是忘记包含端点$0$和$L$，这会错过边缘的有效间隙。 另一个微妙的问题是错误地将行人保留在间隔之外，如果不进行过滤，可能会扭曲顺序。 

## 工作示例

 考虑一个小场景$L = 10$,$C = 5$，还有几个行人。 在给定的时间$T$，假设他们的位置是$1, 5, 9$。 

| 步骤| 具有端点的排序位置 | 计算的间隙 | 最大间隙|
 | ---| ---| ---| ---|
 | 添加端点后 | 0、1、5、9、10 | 1, 4, 4, 1 | 4 |

 由于最大间隙为 4，小于$C$，答案为“N”。 这证实了即使存在多个差距，只有最大的差距才重要。 

现在考虑行人稀疏的情况：

 | 步骤| 具有端点的排序位置 | 计算的间隙 | 最大间隙|
 | ---| ---| ---| ---|
 | 添加端点后 | 0、2、8、10 | 2, 6, 2 | 6 |

 这里2和8之间的差距足够大，所以答案是“Y”。 这表明即使有行人存在，该算法也能正确识别可用的十字路口区域。

 ## 边缘情况

 常见的极端情况是所有行人都在人行横道外。 在这种情况下，持仓列表会变空，算法应该直接处理整个区间$[0, L]$作为单个间隙。 扫描正确产生$L$作为唯一的候选间隙，因此答案为“Y”，如果$L \ge C$。 

另一种情况是多个行人在给定时间倒塌到同一坐标。 排序后，这些重复项不会产生人为间隙，因为连续差异变为零，从而保持了正确性。 

当行人恰好位于$0$或者$L$。 这些必须作为阻塞点包含在内，否则算法将错误地假设比实际存在的边缘间隙更大。
