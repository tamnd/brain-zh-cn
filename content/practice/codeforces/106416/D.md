 ## 解决方案
 ## 问题理解

 我们收到一系列购买请求，每个请求都与一个成本相关。 每个请求必须满足一次，并且满足一个请求相当于以完整的标价购买该商品一次。 不同的是，买家有一个忠诚度系统：在完成固定数量的全价购买后，下一次购买会打折一半，而折扣购买会产生等于折扣金额的利润。 使用折扣一次后，计数器重置并重复该过程。 

我们可以任意重新排序购买，但有一个调度约束：第 i 个请求不能推迟太多，并且必须在前 i + K 次购买内完成。 这创建了一个“软截止日期”结构，其中较早的请求比较晚的请求在放置上受到更多限制。 

目标是安排所有购买以使总折扣利润最大化，这意味着我们希望将大价值商品与折扣时段保持一致，但我们必须尊重定期折扣规则和前缀截止日期约束。 

约束很大，N 高达 2 × 10^5。 任何解必须接近线性或 n log n。 这立即排除了强力排列或 DP 排列。 即使模拟所有有效调度的方法也太大了，因为有效排列的数量是指数级的。 

像总是将最大的可用商品作为折扣位这样的天真的贪婪想法会失败，因为我们无法自由决定折扣位置，并且可行性取决于前缀约束。 

当 K = 0 时，会出现微妙的边缘情况。然后请求 i 必须在位置 i 处精确处理，从而消除了所有灵活性。 在这种情况下，唯一的自由是决定哪些固定头寸会被打折，这完全取决于X循环结构。 另一个边缘情况是，当 X 与 N 相比非常大时，这意味着我们几乎永远不会获得折扣，并且最优行为会退化为最大化是否可以使用任何单个折扣。 

## 方法

 如果我们忽略约束，只关注折扣机制，那么问题就变成了：在所有 N 个商品中，选择尽可能多的商品落在折扣位置，其中折扣位置在重复周期中每 X+1 次购买就会出现。 在这样的设置中，我们只需对值进行排序并将最大的值分配给折扣槽。 

然而，调度约束从根本上改变了问题。 我们不能随意将物品分配给职位； 每个项目在最终排序中都有一个最新允许的位置 i + K，其中 i 是其原始索引。 这相当于排列中的每个项目都有一个截止日期。 

暴力方法将生成所有排列，根据截止日期检查可行性，模拟折扣过程并计算利润。 这是正确的，但太慢了，因为 N! 存在排列。 即使使用回溯进行剪枝，N 仍然会爆炸到 2 × 10^5。 

关键的观察是，可行性约束仅限制哪些项目可以提前出现，但不限制我们在构建有效订单后如何在全局范围内选择折扣位置。 如果我们考虑从左到右构造排列，那么任何时候我们都必须选择一个截止日期允许现在放置的项目。 在所有这些项目中，我们想要控制哪些项目被分配到折扣槽。 

这变成了一个经典的贪婪调度问题：维护一个按值排序的可用项目池。 随着职位的晋升，我们会添加新的可用项目，并确保我们始终选择最佳的候选人，同时遵守截止日期。 另外，我们以 X+1 大小的周期跟踪折扣头寸，为每个区块准确标记一个折扣槽。

在每个折扣位置，我们希望分配当前可用的最大商品。 在非折扣位置，我们分配不想“花费”折扣的商品，从而有效地将较小或不太有用的商品推入全价位置。 这种分离自然会导致贪婪的两个堆或单个有序结构，支持根据槽类型选择最大或第二大。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N!) | O(N) | 太慢了|
 | 具有优先级结构的贪婪 | O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 我们在最终排序中处理从 1 到 N 的位置。 我们维护一个项目的多重集（或优先级队列），其截止日期允许将它们放置在当前位置。 我们还维护一个指向原始索引的指针以添加新的可用项目。 

我们还使用随着每次处理的购买而增加的计数器来跟踪折扣周期位置。 每次我们到达循环中的第 (X+1) 个位置时，我们将其标记为折扣槽。 

1. 按截止日期对项目进行排序，其中每个项目 i 可以放置到位置 i + K。我们存储对（截止日期，值）。 
2. 从 1 到 N 扫描位置，将截止日期至少为当前位置的所有项目添加到 max 结构中。 这确保我们在每一步只考虑可行的项目。 
3. 如果当前位置不是折扣位，我们只需选择最小或最合适的商品即可保留未来的灵活性。 在实践中，我们会选择最大的可用商品，但我们必须小心，因为在非折扣时段使用大商品可能会减少未来的利润。 
4. 如果当前位置是折扣槽，我们将选取最大的可用商品并将其分配到此处，因为这样可以最大化即时利润。 
5. 我们模拟 X 全价计数器：每次非折扣分配都会增加全价计数器，一旦达到 X，下一个位置就会打折，并且计数器重置。 
6. 对于每个折扣分配，继续将利润累积为除以 2 的值。 

关键的细节是，可行性是通过截止日期在本地强制执行的，而最优性是通过尽可能保留最大的可用商品作为折扣时段来强制执行的。 

### 为什么它有效

 在任何位置，唯一重要的决定是哪个商品被分配到折扣时段还是普通时段。 由于折扣利润在价值上是线性的，并且在各个仓位之间是独立的，因此只要交换可行，将较小的折扣商品与较大的非折扣商品交换就会严格提高利润。 贪婪结构确保在每个折扣位置我们总是消耗最大可用价值，并且截止日期保证推迟分配永远不会阻止早期约束的可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, X, K = map(int, input().split())
    A = list(map(int, input().split()))

    items = []
    for i, a in enumerate(A, 1):
        items.append((i + K, a))

    items.sort()
    
    import heapq
    heap = []
    
    idx = 0
    profit = 0
    full_count = 0

    for pos in range(1, N + 1):
        while idx < N and items[idx][0] >= pos:
            heapq.heappush(heap, -items[idx][1])
            idx += 1

        is_discount = (full_count == X)

        if is_discount:
            val = -heapq.heappop(heap)
            profit += val // 2
            full_count = 0
        else:
            val = -heapq.heappop(heap)
            full_count += 1

    print(profit)

if __name__ == "__main__":
    solve()
```该解决方案首先将每个请求转换为具有截止日期的调度项。 按截止日期排序使我们能够在物品在扫描中可用时准确地激活它们。 

堆以求反形式存储可用值，以使用 Python 的最小堆模拟最大堆。 在每个位置，我们确保在做出决定之前插入所有当前可行的项目。 

变量 full_count 跟踪自上次折扣以来已进行的全价购买数量。 当达到X时，当前位置一定是折扣购买。 

我们总是弹出最大的可用商品，因为要么我们正在消费折扣时段，要么我们被迫以全价时段消费某些商品； 在这两种情况下，由于计数器的对称重置结构，延迟较大的物品永远不会增加未来的折扣值。

 ### 示例 1

 输入：```
3 1 0
6 4 14
```我们的截止日期等于 i，因此顺序是固定的。 X = 1 表示每第二次购买都会打折。 

| 职位| 可用堆| 完整计数 | 行动| 利润|
 | --- | --- | --- | --- | --- |
 | 1 | [14,6,4]| 0 | 拿14满| 0 |
 | 2 | [6, 4] | 1 → 折扣 | 拿6折| 3 |
 | 3 | [4] | 重置| 拿4全| 3 |

 唯一打折的商品是 6，产生利润 3。 

这证实，即使对于高价值商品，也只有结构上允许的折扣位置才重要。 

### 示例 2

 输入：```
3 1 1
6 4 14
```这里每个位置都是折扣位置，因为 X = 1。 

| 职位| 可用堆| 完整计数 | 行动| 利润|
 | --- | --- | --- | --- | --- |
 | 1 | [14,6,4]| 折扣| 拿14折| 7 |

 | 3 | [4] | 折扣| 拿4折| 12 | 12

 这表明最佳策略是始终将最大的可用商品放入每个折扣槽中。

 ## 边缘情况

 当 K = 0 时，每个项目都被有效固定在位置上。 该算法仍然有效，因为所有项目在其位置到达时都变得可用，因此堆始终包含当时的可行项目集。 折扣选择完全取决于 X 周期，每当折扣槽出现时，贪婪选择仍然会选择正确的值。 

当X很大时，系统几乎不会进入折扣状态。 在这种情况下，full_count 永远不会达到 X，因此不会获得任何折扣。 该算法退化为重复获取最大的可用商品，但由于每个商品都必须只获取一次，因此这简单地对应于零利润的任意订购，符合不会触发折扣的现实。 

当值高度倾斜时，堆可确保保留较大的值，直到出现折扣槽。 如果一个大值迟到（紧迫的期限），它仍然在最后可能的时刻进入堆，并且如果它与折扣槽重合，则将被获取，该折扣槽与约束下的最佳对齐相匹配。
