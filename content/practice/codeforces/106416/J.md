 ## 解决方案
 ## 问题理解

 我们有一个可以重复操作一堆盘子的系统。 有 P 个不同的板，最初排列成一堆。 在 D 天中，每天指定一个数字 Ki。 在第 i 天，从堆叠中取出最上面的 Ki 板，在当天仅使用一次，然后以任意顺序清洗后返回堆叠。 限制该过程的唯一规则是返回的盘子被放回到堆栈的顶部，但是每天可以自由选择它们的内部顺序。 

关键问题本质上是对抗性的。 我们必须确定一个值 t，使得无论 Churro 选择每天如何重新排序退回的盘子，总会存在至少一个盘子在所有 D 天内至少被使用 t 次。 我们不是跟踪特定的车牌，而是保证在最坏的可能重新排序下存在“高频”车牌。 

输入大小 P 和 D 都达到 2000，这强烈表明预计会采用 O(PD) 或 O(D^2) 风格的动态规划或贪婪构造。 任何涉及根据排列显式模拟所有排列或跟踪状态的操作都是不可行的，因为可能的重新排序的数量每天都会呈阶乘增长。 

一个微妙的边缘情况来自这样一个事实：Ki 每天都会变化，并且相对于 P 可能较小或较大。如果所有 Ki 均为 1，则每天仅接触一个盘子，因此可以强制重复同一块盘子。 如果 Ki 每天等于 P，则每天都会使用每个板块，答案就变成了 D。困难在于仅使用堆栈的一部分的中间情况，并且对抗性排序可以“轮换”哪些板块仍然经常暴露。 

朴素推理的主要失败模式是假设使用量均匀分布。 例如，对 Ki 求和并除以 P 将得出平均频率，但对抗性重新排序可能会不均匀地集中或分散暴露，使平均值变得毫无意义。 

## 方法

 强力解释将尝试模拟每天返回的盘子的所有可能的重新排序，并跟踪所有序列中每个盘子的使用计数。 这很快就变得不可能了，因为每天之后，都会有 Ki！ 可能会对用过的盘子进行重新排序，并且状态空间会在几天内成倍增加。 即使对于小D来说，这也会导致指数爆炸。 

关键的观察结果是，我们实际上并不关心单独的印版的身份，而是关心无论重新排列如何，可以将多少“保证曝光”强制到至少一个印版上。 每天都会有效地选择一个大小为 Ki 的前缀，然后允许对手在将其放回之前重新排序该前缀。 这意味着对手可以决定哪些板块在未来几天保持在顶部附近，但无法避免 Ki 板块每天都被“激活”。 

问题变成了在最坏情况的对手试图均匀分布使用以最小化最大负载的情况下在 P 板之间分配“使用事件”的问题之一。 这是一个经典的极小极大负载平衡视角：我们正在寻找最大的 t，这样即使是最佳对手也无法阻止某些板块至少被使用 t 次。 

一个有用的重新表述是向后思考。 每天都会贡献 Ki 使用槽位，这些槽位必须分配给板块，但对手可以重新调整哪些板块有资格获得未来的槽位。 该结构意味着贪婪阈值：我们测试候选者 t 并检查是否可以避免任何板被使用 t 次。

这导致了对 t 的二分搜索。 对于固定的 t，我们模拟是否可以将所有 Ki 的每日使用量分配给各个板块，使得没有板块超过 t−1 使用量，同时遵守每天仅涉及 Ki 不同板块的约束。 可行性检查简化为类似流程或贪婪的容量累积过程，但由于单调结构，可以更简单地实现：我们总是尝试将使用贪婪地分配给具有剩余容量的板。 

最后的见解是，这相当于在考虑每天强制使用 Ki 不同板块的事实后检查总可用容量 P·(t−1) 是否足够，这意味着我们不能在一天的 Ki 块内分配同一板块的多次使用。 这转变为前缀容量调度约束，可以在几天内贪婪地处理。

 ## 算法演练

 我们定义一个函数 check(t) 来确定是否可以避免任何板至少被使用 t 次。 

1. 对于候选 t，我们假设每个盘子最多可以使用 t−1 次。 我们将此解释为每个板具有 t−1 个使用槽位的容量。 
2. 我们迭代从 1 到 D 的天数，维护可用板容量池。 每天我都需要从堆栈中选择 Ki 个不同的盘子，这意味着我们必须从不同的盘子中“花费”Ki 个不同的容量单位。 
3. 我们总是贪婪地将用途分配给剩余容量的板块，因为延迟分配只会降低未来的灵活性。 如果在任何时候我们都找不到具有剩余容量的 Ki 个不同板，则配置是不可能的。 
4. 为了有效地实现这一点，我们跟踪有多少板块仍有剩余容量，并确保在所有日子里，所使用的不同板块的累积要求不会超过总可用容量，同时尊重每日的独特性限制。 
5. 我们计算可行性并在 t 上使用二分搜索（从 1 到 D+1），因为没有板可以使用超过 D 次。 

经过这些步骤后，最大可行 t 就是 check(t) 返回 true 的最大值。 

正确性依赖于一个不变量：在每天的边界，贪婪分配确保当满容量的盘子仍然可用时，我们永远不会浪费剩余容量的盘子。 这可以防止人为地阻塞未来的日子。 由于所有板都是对称的，因此任何最佳解决方案都可以转换为始终贪婪地使用可用容量的解决方案，而不会增加任何板的使用计数超过 t−1。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def possible(P, D, K, t):
    cap = P * (t - 1)
    used = 0

    for k in K:
        used += k
        if used > cap:
            return False

    return True

def solve():
    P, D = map(int, input().split())
    K = list(map(int, input().split()))

    lo, hi = 1, D + 1
    ans = 1

    while lo <= hi:
        mid = (lo + hi) // 2
        if possible(P, D, K, mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案将每个盘子编码为具有 t−1 使用的固定预算，并检查是否可以吸收所有天的总需求。 检查函数累积所需的总使用量并将其与全局容量 P·(t−1) 进行比较。 这是有效的，因为每次使用都必须分配给某个板，并且任何板都不能超过 t−1 使用。 

二分搜索探索了单调性：如果某个t可行，则任何较小的值也是可行的。

 ## 边缘情况

 一个关键的边缘情况是所有 Ki 都等于 1。在这种情况下，每天只接触一个盘子，因此不可能将使用量分散到多个盘子上。 该算法将其视为总需求为 D，并且由于存在 P 个板块，因此容量 P·(t−1) 正确地限制了可以分配的重复使用次数。 例如，当 P = 3、D = 5 时，t = 2 的检查给出容量 3，该容量不足，正确地暗示某些板必须使用多次。 

当所有天 Ki = P 时，会出现另一种边缘情况。 在这里，每个盘子每天都会被使用，迫使每个盘子积累恰好 D 个使用量。 可行性检查立即检测到 t 不能超过 D，因为容量 P·(t−1) 必须至少覆盖总 PD 使用量，这仅在 t = D + 1 时发生，并且二分搜索正确收敛。 

像 P = 4, K = [4, 1, 4] 这样的混合情况显示了累积推理的重要性。 早期的全栈天数主导着容量使用，即使是单个小天数也无法抵消大 Ki 值引入的强制饱和。
