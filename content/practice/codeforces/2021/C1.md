 ## 问题理解

 我们给出了最初的人员阵容，每个人只出现一次。 一系列演示必须按固定顺序进行，并且每个演示都分配给特定的人。 

在每一步中，当前位于队列前面的人都会提供下一张幻灯片。 交付后，我们可以立即将同一个人插入队列中稍后的任何位置，保持所有其他人的相对顺序不变。 这是阵容发展的唯一途径。 

问题是我们是否可以安排这些移动，以便每张幻灯片所需的人员在需要时准确地出现在前面。 

所以这个过程是受到限制的：我们总是“消耗”前面的人，并且只有在他们发言后我们才被允许重新定位同一个人。 我们不能让任意的人站出来； 我们只能回收刚才说话的那个。 

核心困难在于，一线行为迫使我们进行一系列暴露，这些暴露序列由初始顺序以及我们如何回收扬声器决定。 

约束条件很大，测试用例中 n 和 m 的总数高达 2⋅10^5。 这排除了每一步重复扫描或重建列表的任何模拟。 任何甚至是 O(nm) 的解决方案都是不可能的，即使是 O(m log n) 也只有在仔细实施的情况下才是可接受的。 预期的解决方案必须是线性或接近线性的。 

当我们假设我们总是可以通过循环其他人来“等待”所需的人时，就会出现一个微妙的失败案例。 例如，如果所需的序列请求一个已经通过的人，而该人在不违反排序约束的情况下无法到达，则天真的贪婪指针模拟可能会错误地接受。 

关键的困难是认识到，一旦一个人在相对于当前指针的初始顺序中“被跳过”，我们必须有一个一致的方法来解释他们何时可以重新出现在前面。 

## 方法

 暴力模拟将明确地维持人员队列。 每一步都会采取前面的方式，检查它是否与所需的扬声器相匹配，然后为该人尝试所有可能的插入位置。 即使我们贪婪地模拟选择，我们仍然会更新大小为 n 的列表最多 m 次，这会导致最坏情况下的 O(nm) 行为。 

关键的观察是我们实际上不需要模拟完整的列表。 我们只需要知道是否能够以与初始排列一致的方式“消费”所需的序列。 

考虑从左到右扫描初始订单。 我们可以将这个过程解释为尝试使用初始数组 a 来匹配所需的序列 b，但有一个特殊的规则：一旦我们传递了 a 中的一个位置，我们就无法返回到它，除非先前匹配的结构允许通过重新排列实现“重置”效果。 

这导致初始排列的贪婪匹配过程。 我们在 a 中维护一个指针，表示最早未使用的元素。 对于 b 中的每个必需元素，我们尝试从该指针开始找到它。 如果我们找到了它，我们就会前进。 如果我们在剩余的后缀中找不到它，那么它仍然出现的唯一方法是它是否已经在我们可以回收的段中较早使用过，这会强制重新启动条件。 在简单版本中，这进一步简化了：如果我们可以将 b 模拟为重复循环扫描的子序列，则该序列是有效的，其中每个段不需要多次回绕。 

更具体地说，我们模拟重复按顺序扫描a，但确保一旦我们从头开始扫描，这是因为我们已经消耗了至少一个全通边界。 如果所需的元素出现在当前指针之前，而我们还没有完成完全换行，这是不可能的。

这减少了跟踪元素的位置并确保位置序列不递减，除了当我们逻辑上完成一个循环时，我们被允许从结束到开始恰好重置一次。 

所以我们将每个值的位置存储在a中。 在迭代 b 时，我们强制要求仓位必须严格增加； 如果不是，我们增加周期计数器并继续，但如果超过允许的周期，我们拒绝。 

在这个版本中，由于 q = 0，我们只评估一次。

 ## 算法演练

 1. 建立字典`pos`在哪里`pos[x]`是价值指数`x`在初始数组中`a`。 这将元素查找转换为 O(1) 操作。 
2. 初始化变量`cur`到 0，代表最小允许位置`a`为下一个需要的发言者。 
3. 初始化变量`cycles`到 0。这计算了我们被迫“换行”超过数组末尾的次数。 
4. 迭代每个所需的发言人`x`在`b`：

- 让`p = pos[x]`。 
- 如果`p >= cur`，我们可以在当前扫描中使用这个事件，所以我们设置`cur = p + 1`。 
- 否则，我们需要从头开始重新扫描`a`，所以我们增加`cycles`并设置`cur = p + 1`。 
5. 如果在任何时候`cycles > 1`，立即输出“TIDAK”。 
6. 如果循环完成且未违反循环约束，则输出“YA”。 

关键的想法是，每次我们回绕时，我们都承诺从一开始就再次使用排列的结构，并且在过程的约束下，这只能一致地发生一次。 

### 为什么它有效

 不变的是`cur`始终表示初始排列中的最早位置，该位置仍然与已匹配说话者的序列一致，假设最多发生一次重置。 每当我们按排列顺序向后移动时，我们都被迫将剩余的过程重新解释为开始一次新的遍历。 由于允许移动的结构除了回收前面的元素之外绝不会产生任意的重新排序，因此无法一致地解决不止一次的完全重置。 因此，当我们可以使用最多一个这样的重置来模拟它，同时保留每个段内递增的位置顺序时，该序列正是有效的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    pos = [0] * (n + 1)
    for i, v in enumerate(a):
        pos[v] = i
    
    cur = 0
    cycles = 0
    
    for x in b:
        p = pos[x]
        if p >= cur:
            cur = p + 1
        else:
            cycles += 1
            cur = p + 1
            if cycles > 1:
                print("TIDAK")
                break
    else:
        print("YA")

if __name__ == "__main__":
    solve()
```The implementation begins by mapping each value to its position in the initial ordering, which allows constant-time access to where each required speaker originally sits.

 变量`cur`通过排列强制单调进展。 当下一个所需位置违反这种单调性时，我们将其解释为需要从数组的开头重新开始扫描，由`cycles`。 

提前退出时`cycles > 1`一旦我们知道序列无法实现，就可以防止不必要的处理。

 ## 边缘情况

 当序列在排列顺序中重复强制向后跳跃时，就会出现临界边缘情况。 例如，如果所需的序列在位于初始数组相对两端的元素之间交替，则每个步骤都可能强制重置。 一旦需要第二次重置，算法就会正确地拒绝这种情况，因为`cycles`超过1。 

另一个边缘情况是当`b`已经是`a`。 在那种情况下，`cur`只向前移动，不会发生循环，所以答案立即被接受。 

一个最小的案例`n = 1`不管怎样总是成功`m`，因为没有顺序冲突并且`pos[x]`始终为零，永远不会违反单调性。
