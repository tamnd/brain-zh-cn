 ## 解决方案
 ## 问题理解

 在这个问题中，我们给出了一个村庄，表示为一个连通图，其中房屋作为节点，互联网电缆作为边。 每个边缘都有一个延迟，表示沿该电缆传输数据的延迟。 部分房屋需要互联网接入，我们最多可以放置服务器`k`房屋，哪里`k`范围可以从`1`到`n`。 一旦放置了服务器，任何具有互联网的房屋都可以沿着图中的路径连接到服务器，并且该房屋所经历的延迟是沿着该路径的边缘中最大的延迟。 

任务是确定每个可能的服务器数量`k = 1..n`，可以实现的最小总延迟，对所有需要互联网的房屋进行求和。 每个查询都涉及计算最佳服务器放置位置以及从服务器到需要互联网的房屋的最佳路径。 输出是每个的最小总和的列表`k`。 

约束表明该图很小：最多 400 个节点和 400 条边。 这使我们能够使用运行在`O(n^3)`时间，例如计算所有对最短路径的 Floyd-Warshall，因为`400^3 = 64,000,000`操作，在 2 秒的时间限制内是可以接受的。 

一个不明显的边缘情况是，所有需要互联网的房屋都已经与单个节点相邻，因此放置一台服务器可以完全满足它们，并且零延迟增加。 当图具有形成瓶颈的高延迟边缘时，会发生另一种微妙的情况； 如果忽略路径上的最大边缘度量，服务器的天真贪婪放置可能会低估真正的最小总延迟。 

## 方法

 暴力方法是枚举所有组合`k`用于服务器放置的房屋，并且对于每种组合，计算从服务器到所有所需房屋的路径上的最大延迟。 这是正确的，但不可行，因为组合的数量是`C(n, k)`并迅速爆炸为中等`n`和`k`。 

关键的见解是将最短路径（或最小最大边缘路径）的计算与服务器的选择分开。 由于度量是沿路径的最大边缘延迟，因此我们可以使用改进的 Floyd-Warshall 算法预先计算每对房屋的最小可能最大边缘，其中路径成本定义为沿路径的最大权重而不是总和。 一旦我们有了所有对之间的最小最大边路径矩阵，我们就可以使用动态规划来选择最多`k`服务器职位。 对于简单版本，`k`可以大到`n`，所以我们可以简单地考虑以增量贪婪的方式在每个需要互联网的房子放置一台服务器，因为添加更多服务器永远不会增加总延迟。 

| 方法| 时间复杂度| 空间复杂度| 判决|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^k * n * m) | O(n^k * n * m) | O(n^2) | O(n^2) | 太慢了|
 | 最优（最大边缘 Floyd-Warshall + 贪婪 DP）| O(n^3 + n*p) | O(n^3 + n*p) | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 1. 初始化一个`n x n`矩阵`max_edge[i][j]`存储沿任意路径的最小可能最大边`i`到`j`。 充满`max_edge[i][j]`与直接边权重如果`i`和`j`是相连的，否则无穷大。 
2. 应用适用于最大边缘度量的 Floyd-Warshall 算法。 对于每个中间节点`k`， 更新`max_edge[i][j] = min(max_edge[i][j], max(max_edge[i][k], max_edge[k][j]))`。 这确保了对于任何一对`(i, j)`,`max_edge[i][j]`包含沿连接它们的路径的最小最大边。 
3. 对于每个所需的房屋，使用以下方法构建所有其他节点的最小延迟列表：`max_edge`矩阵。 房屋的延迟`s`到服务器`v`是`max_edge[s][v]`。 
4. 迭代`k`从`1`到`n`。 对于每个`k`， 选择`k`最大限度地减少延迟总和的服务器位置。 在简单版本中，因为`k`可以大到`n`，我们可以贪婪地考虑按顺序在所有房屋中放置服务器，这会产生每个房屋的最小总延迟`k`。 
5. 输出每个的总延迟`k`。 

为什么有效：Floyd-Warshall 步骤保证对于任何需要互联网的房屋和任何候选服务器，我们都知道沿任何路径的最小最大延迟。 通过评估所有房屋作为潜在服务器并累积最小延迟，我们获得了任何其他组合都无法改善的总和，因为我们考虑了每条路径和每个节点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, p = map(int, input().split())
        s = list(map(lambda x: int(x)-1, input().split()))
        INF = 10**18
        max_edge = [[INF]*n for _ in range(n)]
        for i in range(n):
            max_edge[i][i] = 0
        for _ in range(m):
            u, v, w = map(int, input().split())
            u -= 1
            v -= 1
            max_edge[u][v] = w
            max_edge[v][u] = w

        # Floyd-Warshall for minimal max-edge paths
        for k in range(n):
            for i in range(n):
                for j in range(n):
                    max_edge[i][j] = min(max_edge[i][j], max(max_edge[i][k], max_edge[k][j]))

        # Compute minimal total latency for each number of servers
        latencies = [INF]*n
        # Start with no servers: all latency to nearest server
        # Greedy: start with server at each house one by one
        best_latency = [INF]*n
        # Initially, zero servers placed
        min_latency_per_house = [INF]*p

        result = []
        # Place servers one by one
        for k in range(1, n+1):
            # Choose the next best server to minimize sum
            best_improvement = -1
            best_house = -1
            for v in range(n):
                # compute improvement if placing server at v
                improvement = 0
                for idx, house in enumerate(s):
                    improvement += max(0, min_latency_per_house[idx] - max_edge[house][v])
                if improvement > best_improvement:
                    best_improvement = improvement
                    best_house = v
            # Update min_latency_per_house
            for idx, house in enumerate(s):
                min_latency_per_house[idx] = min(min_latency_per_house[idx], max_edge[house][best_house])
            result.append(str(sum(min_latency_per_house)))
        print(' '.join(result))

if __name__ == "__main__":
    solve()
```代码首先构造了`max_edge`使用 Floyd-Warshall 矩阵计算任意节点对之间的最小最大延迟。 对于每个可能的服务器数量，它会贪婪地选择为需要互联网的房屋提供最大总延迟改善的节点。 更新每个房屋的最小延迟后，它会累积总数并将其附加到输出中。 注意在内部从零开始索引节点以简化数组访问。 这里不需要刷新和读取，因为问题不是交互式的。
