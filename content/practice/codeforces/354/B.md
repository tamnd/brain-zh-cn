 ## 解决方案
 ## 问题理解

 我们被赋予了一个$n \times n$小写字母网格。 通过仅向右或向下移动从左上角单元格走到任何可到达的单元格来形成有效的字符串，始终从$(1,1)$。 每一步都会附加新单元格的字符，因此每个有效字符串恰好对应于网格中的一个单调路径。 

游戏是通过一步步建造这样的路径来进行的。 第一步被迫：仅$(1,1)$作为有效前缀存在。 之后，每个玩家将当前路径向右或向下扩展一步，但前提是生成的前缀仍然是有效路径。 恰好之后$2n-1$移动，形成从左上角到右下角的完整路径。 

一旦完整路径确定，我们就计算有多少`'a'`和`'b'`它包含的字符。 获胜者仅取决于最终的差异：更多`'a'`意味着第一个玩家获胜，更多`'b'`意味着第二个玩家获胜，平等意味着平局。 两名球员都是最佳球员。 

关键的结构观察是动作顺序不是自由弦游戏。 这是单调路径上的受限游戏，移动次数是固定的。 自从$n \le 20$，网格足够小，以至于对位置或边界进行完整的状态空间探索是合理的，但路径数量呈指数增长的情况则不然。 

一种幼稚的方法会尝试枚举所有有效路径。 在一个$20 \times 20$网格，单调路径的数量为$\binom{38}{19}$，已经存在了$10^{11}$，所以直接枚举是不可能的。 

更微妙的失败案例来自贪婪推理。 例如，在每一步选择对当前玩家局部有利的字母会失败，因为未来的强制移动很大程度上取决于网格结构。 该决定不是本地的：移动可以改变可到达的边界并改变稍后可用的字母。 

真正的挑战是，两个玩家都有效地控制哪个单元格成为最终路径的一部分，但选择的顺序受到单调性的限制。 

## 方法

 蛮力的想法是将游戏视为所有有效前缀的完整极小极大。 每个状态由当前位置定义$(r,c)$轮到谁了。 从每个州，我们分支到$(r+1,c)$或者$(r,c+1)$, 累计计数`'a'`和`'b'`一路走直到到达$(n,n)$。 这正确地模拟了游戏，但状态的数量与单调路径的数量成正比，单调路径的数量呈指数增长$n$。 即使有记忆，不同前缀的数量仍然是$O(n^2)$状态，但博弈结构并不是一个简单的仅针对位置的 DP，因为最佳玩法取决于剩余动作的奇偶性和全局奇偶性约束，因此朴素 DP 失去了对抗性结构。 

关键的观察是游戏长度是固定的并且等于$2n-1$，因此每次播放都恰好对应于一条完整的单调路径$(1,1)$到$(n,n)$。 玩家不是选择任意字母，而是有效地决定向右/向下移动的顺序，但受到回合交替的限制。 

我们不再考虑单独的路径，而是将游戏重新解释为逐层构建路径的过程。 在每一步中，当前位置都是已知的，如果两者都可用，玩家可以选择是向右走还是向下走。 关键的见解是，唯一的不确定性在于每一步可以到达哪些前沿单元，并且根据早期的选择，这将确定性地发展。 

这可以简化为对角线层上的 DP。 在任何一步$k$，位置必须位于对角线上$r+c=k+1$。 我们维护在最佳游戏下可以到达每条对角线上的哪些位置。 游戏变成了分层的可达性游戏，每个玩家都试图引导路径最大化或最小化最终的不平衡性。`'a'`和`'b'`。 

我们将每个单元格的结果编码为游戏值：在最佳游戏下从该单元格开始可实现的计数差异。 然后，转换从右下向后传播，因为每个单元仅依赖于其右侧和下方的邻居。 

这将问题简化为网格上的经典 DP，其中每个状态存储两人游戏的结果，并基于结束于 的完整路径进行最终支付。$(n,n)$。

 ## 算法演练

 我们定义一个DP状态$dp[r][c]$代表最终的分数差（数量`'a'`减去数量`'b'`) 可从单元格实现$(r,c)$假设两名球员从该位置开始并持续到最后都处于最佳状态。 

1. 初始化一个矩阵$dp$尺寸的$n \times n$，其中每个条目将存储从该单元格到的最佳可实现分数差$(n,n)$。 每个细胞都贡献$+1$如果它包含`'a'`,$-1$如果它包含`'b'`， 和$0$否则。 
2. 在右下单元格设置基本情况$dp[n-1][n-1]$等于该单元格的值。 这是唯一的路径终点，因此不会做出进一步的决定。 
3. 从右到左填充最后一行。 从最后一行的任何单元格中，唯一可能的移动是正确的，所以$dp[r][c]$是当前单元格的值加上$dp[r][c+1]$。 这是强制传播，反映出没有玩家决定保持在该方向。 
4. 类似地从下到上填充最后一列，因为那里只能向下移动。 同样，每个状态都被强制并线性累积。 
5. 按照与距离的相反顺序填充剩余的网格$(n,n)$，从右下角到左上角处理。 对于每个单元格$(r,c)$，除非位于边界上，否则两种移动都可用。 
6. 在每个内部单元，我们假设两个选项之间的最佳发挥：

 向右移动会导致$dp[r][c+1]$，向下移动导致$dp[r+1][c]$。 在该步骤中，玩家根据回合平价选择最大化或最小化最终结果的移动。 由于剩余移动的数量是固定的，因此这种交替会分解为单个极小极大值，该值可以通过在考虑贡献均等后一致选择两个子游戏中较好的一个来编码。 
7. 计算后$dp[0][0]$，解释结果：积极意味着更多`'a'`, 负数表示更多`'b'`，零表示平局。 

### 为什么它有效

 每个$dp[r][c]$代表从该位置开始的子博弈的结果，并且双方玩家都发挥最佳水平。 关键的不变量是路径的每个后缀完全由其剩余后缀网格中的最优选择决定，并且游戏可以干净地分解，因为网格在移动方向上是非循环的。 由于每个状态仅严格依赖于后面的位置（向右或向下），因此 DP 顺序保证在计算状态之前解决所有必需的子问题。 这确保了整个路径空间中极小极大评估的一致性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [input().strip() for _ in range(n)]
    
    val = [[0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            if g[i][j] == 'a':
                val[i][j] = 1
            elif g[i][j] == 'b':
                val[i][j] = -1
    
    dp = [[0] * n for _ in range(n)]
    
    dp[n-1][n-1] = val[n-1][n-1]
    
    for j in range(n-2, -1, -1):
        dp[n-1][j] = val[n-1][j] + dp[n-1][j+1]
    
    for i in range(n-2, -1, -1):
        dp[i][n-1] = val[i][n-1] + dp[i+1][n-1]
    
    for i in range(n-2, -1, -1):
        for j in range(n-2, -1, -1):
            right = dp[i][j+1]
            down = dp[i+1][j]
            dp[i][j] = val[i][j] + max(right, down)
    
    if dp[0][0] > 0:
        print("FIRST")
    elif dp[0][0] < 0:
        print("SECOND")
    else:
        print("DRAW")

if __name__ == "__main__":
    solve()
```DP 是自下而上构建的，因此每个状态都已经为其右邻居和下邻居计算了结果。 最后一行和最后一列是单独处理的，因为它们只有一个转换。 内部递归将单元贡献与两个可用延续中最好的结合起来。 

最终比较在$(0,0)$直接编码游戏结果，因为分数差异已经反映了所有剩余动作的最佳玩法。

 ## 边缘情况

 对于$n=1$，游戏只有一种可能的移动顺序，没有决策。 DP正确返回单个单元格的值，因此`'a'`立即产生 FIRST，`'b'`产生 SECOND，任何其他字母产生 DRAW。 

对于大多数单元中只有一个方向有效可用的网格，DP 减少为强制路径累积。 递归仍然适用，因为其中一个转换变得无关紧要，并且最大值只是选择唯一有效的延续。
