 ## 解决方案
 ## 问题理解

 我们从一个正整数数组开始。 对于每个元素，我们最多可以减少它`k`，并且该值必须保持正值。 在每个位置独立执行这些减少之后，我们希望结果数组的最大公约数尽可能大。 

表达该任务的另一种方式是：找到最大的整数`g`使得每个原始值`a[i]`可以向下调整到某个正倍数`g`，同时最多改变它`k`。 

对于固定候选gcd`g`，问题变得非常具体。 每个数都可以`a[i]`达到的倍数`g`区间内`[a[i] - k, a[i]]`？ 如果是，那么`g`是可以实现的。 如果连一个元素都达不到这样的倍数，那么`g`是不可能的。 

这些限制迫使我们仔细思考复杂性。 数组长度达到`3 * 10^5`，值达到`10^6`。 任何直接比较所有对或测试每个除数与每个元素的算法都会太慢。 甚至一个`O(n * maxA)`方法将大致达到`3 * 10^11`最坏情况下的操作。 由于取值范围只有`10^6`，预期的解决方案几乎肯定会在值域上利用数论结构，而不是在数组本身上进行大量迭代。 

一些边缘情况很容易被错误处理。 

认为`k = 0`。```
3 0
6 10 14
```答案是`2`，因为我们无法改变任何事情。 假设每个数字总是可以移动到附近的倍数的粗心实现可能会错误地接受更大的 gcd 值。 

当一个值已经小于候选 gcd 时，就会出现另一种微妙的情况。```
2 3
2 100
```尝试`g = 5`立即失败，因为第一个数字不能成为的正倍数`5`。 最接近的较低倍数是`0`，但价值观必须保持积极。 

间隔也很重要。 考虑：```
2 2
7 13
```为了`g = 5`，第一个数字可以变成`5`，但第二个数字不能变成`10`因为这需要减少`3`。 正确答案是`1`。 一个不正确的实现，只检查`a[i] % g <= k`在不处理精确可达的多个逻辑的情况下，可以默默地接受无效的情况。 

最重要的观察结果是，对于一些`x`, 的倍数`g`存在于`[x-k, x]`确切的时间：```
floor(x / g) > floor((x-k-1) / g)
```这种区间解释是高效解决方案的核心。 

## 方法

 蛮力的想法很简单。 我们尝试一切可能的gcd`g`从`1`最多`max(a)`，对于每个数组元素，我们检查是否是某个倍数`g`位于里面`[a[i]-k, a[i]]`。 

对于一个号码`x`，最大可达倍数`g`是：```
(x // g) * g
```如果这个倍数是正数并且至少`x-k`， 然后`x`可以为GCD做出贡献`g`。 

这个逻辑是正确的，因为任何结果值都必须是最终 gcd 的倍数。 如果每个元素都可以独立达到某个倍数`g`，那么我们可以构造一个整个数组，其 gcd 可被整除`g`。 

问题是运行时。 最多有`10^6`候选 GCD 值最多`3 * 10^5`数组元素。 直接实现大致执行`3 * 10^11`检查，这是完全不可行的。 

关键的见解是我们实际上不需要检查每个 gcd 候选者的每个数组元素。 重要的是哪些值存在，而不是它们出现在哪里。 因为所有的值最多都是`10^6`，我们可以在值域上构建频率数组并有效地回答范围查询。 

对于候选gcd`g`，考虑连续倍数之间的所有间隔：```
[t*g, (t+1)*g - 1]
```该区间内的每个数字只能向下移动到倍数`t*g`。 仅当数量最多为`k`大于`t*g`。 

所以在区间内，有效数字是：```
[t*g, t*g + k]
```所有大于该值的数字都无法通过 gcd`g`。 

这将问题转化为值轴上的区间覆盖。 使用频率上的前缀和，我们可以快速计算每个块的无效区域内有多少数字。 如果存在任何无效数字，则 gcd 候选失败。 

总复杂度变得和谐：```
maxA/1 + maxA/2 + maxA/3 + ...
```这大约是`maxA * log(maxA)`并且很容易足够快`10^6`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(n * maxA)`|`O(1)`| 太慢了 |
 | 最佳 |`O(maxA log maxA)`|`O(maxA)`| 已接受 |

 ## 算法演练

 1.读取数组并计算`MAX = max(a)`。 
2.构建频率数组`freq`在哪里`freq[x]`存储多少倍的值`x`出现。 
3. 构建频率上的前缀和数组。 

这使我们能够计算有多少数组元素位于任何值区间内`[L, R]`在恒定的时间内。 
4. 迭代每个可能的 gcd 候选者`g`从`MAX`下降到`1`。 

我们向下迭代，因为第一个有效的 gcd 自动是最大答案。 
5. 对于每个多重块`[m, m+g-1]`，确定哪些数字无效。 

号码来自`m`到`m+k`可以减少到`m`。 

号码来自`m+k+1`到`m+g-1`不能达到任意倍数`g`。 
6. 使用前缀和来计算每个无效区域内有多少个数组值。 

如果那里有一个值，那么 gcd`g`是不可能的。 
7. 如果所有块都不包含无效数字，则打印`g`并终止。 

### 为什么它有效

 对于固定的 gcd`g`，每个数字必须成为某个倍数`g`至多减少后`k`。 

区间内`[m, m+g-1]`，唯一可达到的低于数字的倍数是`m`。 一个值`x`在这个区块可以达到`m`确切的时间：```
x - m <= k
```所以有效区域是`[m, m+k]`，上面的内容都无效。 

该算法检查整个值域中的每个此类无效区域。 如果没有数组元素落入无效区间，则每个数字都可以达到`g`， 所以`g`是可以实现的。 如果某个值确实落入无效区间，则该元素不存在合法调整，从而使得`g`不可能的。 

由于我们从最大到最小测试 gcd 候选，第一个有效的就是最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    MAX = max(a)

    freq = [0] * (MAX + 1)

    for x in a:
        freq[x] += 1

    pref = [0] * (MAX + 1)
    pref[0] = freq[0]

    for i in range(1, MAX + 1):
        pref[i] = pref[i - 1] + freq[i]

    def range_count(l, r):
        if l > r or l > MAX:
            return 0

        r = min(r, MAX)

        if l == 0:
            return pref[r]

        return pref[r] - pref[l - 1]

    for g in range(MAX, 0, -1):
        ok = True

        m = 0

        while m <= MAX:
            bad_l = m + k + 1
            bad_r = m + g - 1

            if range_count(bad_l, bad_r) > 0:
                ok = False
                break

            m += g

        if ok:
            print(g)
            return

solve()
```实现直接遵循数学结构。 

频率数组将整个输入压缩为值计数。 由于所有数字最多为`10^6`，迭代值域是足够有效的。 

前缀和数组是主要的优化。 如果没有它，检查无效区间是否包含元素将需要每次扫描整个区间。 前缀和将其减少到恒定时间。 

循环结束`g`从最大到最小运行，因此一旦找到有效的 gcd，我们就可以立即停止。 

内循环处理大小的块`g`。 对于起始于的块`m`，无效区域为：```
[m + k + 1, m + g - 1]
```那里的值远远高于最近的较低倍数。 

一个微妙的细节是修剪间隔`MAX`。 某些间隔超出了最大数组值，并且在前缀数组之外查询会导致错误。 

另一个重要的细节是处理`m = 0`。 街区`[0, g-1]`表示小于的数字`g`。 Since resulting values must stay positive, numbers in`(k, g-1]`无效，因为它们需要减少到`0`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(MAX log MAX)`| 所有 gcd 候选者的调和级数 |
 | 空间|`O(MAX)`| 频率和前缀数组 |

 这里`MAX`是最大数组值，最多`10^6`。 

谐波复杂度来自于倍数的迭代：```
MAX/1 + MAX/2 + MAX/3 + ...
```其行为类似于`MAX log MAX`。 

这很容易符合以下限制`MAX = 10^6`。

 ## 边缘情况

 考虑不允许修改的情况。```
3 0
6 10 14
```该算法向下检查 gcd 候选者。 为了`g = 3`, 块`[9,11]`有无效间隔`[10,11]`，和值`10`存在在那里，所以`3`失败。 为了`g = 2`，每个数字都已经位于`2`，因此所有无效区间均为空。 算法正确返回`2`。 

现在考虑小于候选 gcd 的值。```
2 3
2 100
```尝试`g = 5`，第一个块是`[0,4]`。 有效号码仅`[0,3]`。 价值`2`很好，因为它只能在概念上减少到零，但正倍数很重要。 后面的块最终会失败，因为`100`无法在一定距离内正确对齐`3`。 该算法自然地通过从以下位置开始的块来处理这些小值区域：`0`。 

最后，检查一下经典的差一陷阱。```
2 2
7 13
```为了`g = 5`, 块`[10,14]`有有效号码`[10,12]`和无效数字`[13,14]`。 自从`13`位于无效区域，算法拒绝`5`。 

这是完全正确的，因为转动`13`进入`10`需要减少`3`，这超过了`k = 2`。
