 ## 解决方案
 ## 问题理解

 我们得到一个仅由字符组成的字符串`A`和`B`。 我们可以重复删除等于的任何相邻子串`AB`或者`BB`。 移除这样的一对后，绳子的剩余部分连接在一起，可能会创建新的可移除对。 

对于每个测试用例，我们需要在执行任意数量的有效删除后确定字符串的最小可能长度。 

所有字符串的总长度最多为`2 × 10^5`，这是真正重要的约束。 任何重复扫描字符串并物理删除字符的算法很容易变得二次。 二次解大约需要`4 × 10^10`最坏情况下的操作，远远超出了极限。 我们需要一种线性时间方法，仅处理每个字符恒定的次数。 

有几种情况很容易误判。 

考虑字符串：```
AB
```答案是`0`，因为整个字符串可以在一次操作中删除。 

现在考虑：```
BA
```答案是`2`。 没有`AB`或者`BB`子字符串，因此无法删除任何内容。 只计算数量的解决方案`A`和`B`字符会错误地将这两个字符串视为相同。 

另一个微妙的例子是：```
ABB
```一种可能的顺序是：```
ABB → A → 1
```首先删除最后一个`BB`，离开`A`。 或者：```
ABB → B → 1
```消除`AB`第一的。 不同的操作顺序产生不同的中间字符串，但可达到的最小长度是相同的。 该解决方案不得依赖于选择特定的删除顺序。 

最后一个棘手的情况是：```
BBB
```我们可以删除一个`BB`一对：```
BBB → B
```答案是`1`， 不是`0`。 每当一个块包含奇数个`B`字符和没有`A`可以取消最后一项，一项`B`幸存下来。 

## 方法

 直接模拟会重复搜索出现的情况`AB`或者`BB`，删除其中一个，连接剩余部分，继续下去，直到不存在任何移动为止。 

这种做法是正确的，因为它确实遵循了游戏规则。 问题是效率。 每次删除可能需要移动几乎整个字符串，并且最多可以有`O(n)`删除。 一个长度的字符串`n`因此可以要求`O(n²)`工作。 

关键的观察结果是，两个可移动模式都以`B`。 

假设我们从左到右处理字符串并维护当前未缩减的字符串。 当我们读到一个新字符时：

 如果是的话`A`，它不能立即形成可移除对，因此它必须暂时保留。 

如果是的话`B`，那么任何先前的字符都允许删除：```
AB → removed
BB → removed
```唯一重要的是当前缩减字符串中紧邻其之前是否存在字符。 如果有的话，新的`B`删除该字符。 如果没有，则`B`幸存下来。 

这种行为正是堆栈所提供的。 

我们将当前未缩减的字符存储在堆栈中。 

读书时`A`，推一下。 

读书时`B`：

 如果堆栈非空，则弹出一个字符。 弹出的字符与此一起`B`对应于任一`AB`或者`BB`删除。 

如果栈为空，则压栈`B`，因为没有任何东西可以用它来删除。 

处理完整个字符串后，堆栈中正好包含无法消除的字符。 它的大小就是答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 创建一个空堆栈。 
2. 从左到右扫描字符串。 
3. 如果当前字符是`A`，将其压入堆栈。 

一个`A`单独不能完成任一可移动模式。 
4. 如果当前字符是`B`并且栈非空，弹出栈顶元素。 

弹出的字符与当前字符一起`B`形式要么`AB`或者`BB`，两者都是可拆卸的。 
5. 如果当前字符是`B`并且栈为空，push`B`。 

由于没有可用的前导字符，因此无法删除。 
6. 处理完所有字符后，输出堆栈大小。 

### 为什么它有效

 堆栈始终表示迄今为止处理的前缀的最短可能剩余字符串。 

当一个新的`B`到达后，任何现有的顶级角色都可以立即与其配对。 那个顶级角色是否是`A`或者`B`，该对消失。 保留任何一个角色都不会有助于产生更短的最终结果，因为两者`AB`和`BB`是有效的删除。 

如果堆栈为空，则`B`没有伙伴，必须留下来。 未来的操作如果不先在其前面放置另一个字符就无法删除它，这是不可能的，因为我们按原始顺序处理字符。 

通过对处理后的前缀进行归纳，堆栈完全保持该前缀的完全简化形式。 当扫描结束时，其长度是可达到的最小最终长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        s = input().strip()

        stack = []

        for ch in s:
            if ch == 'A':
                stack.append('A')
            else:
                if stack:
                    stack.pop()
                else:
                    stack.append('B')

        answers.append(str(len(stack)))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```该解决方案遵循上述堆栈模拟。 

堆栈存储到目前为止处理的前缀的简化形式。 每一个`A`被推送是因为它无法立即参与删除。 

当一个`B`看来，只有两种可能。 如果栈非空，则栈顶元素和当前元素`B`一起消失。 这与两个允许的操作相匹配。 如果堆栈为空，则`B`生存下来并且必须被储存。 

一个常见的错误是明确检查顶部是否是`A`或者`B`。 这是不必要的，因为两者`AB`和`BB`是可拆卸的。 唯一重要的是角色是否存在。 

另一个容易出现的错误是忘记了幸存的`B`必须在堆栈为空时压入。 如果没有这一步，类似的情况`"B"`或者`"BBB"`产生不正确的答案。

 ## 边缘情况

 考虑：```
1
BA
```堆栈的演变是：```
B -> [B]
A -> [B, A]
```不`B`决赛后抵达`A`，因此无法删除任何内容。 最终尺寸为`2`。 该算法正确地避免删除不相邻的字符。 

考虑：```
1
BBB
```堆栈的演变是：```
B -> [B]
B -> []
B -> [B]
```一`BB`一对消失了，但最后一个`B`幸存下来。 最终尺寸为`1`，匹配最优结果。 

考虑：```
1
AB
```堆栈的演变是：```
A -> [A]
B -> []
```整个字符串消失，产生答案`0`。 

考虑：```
1
ABB
```堆栈的演变是：```
A -> [A]
B -> []
B -> [B]
```答案是`1`。 这个例子说明了为什么算法不需要在不同的删除顺序之间进行选择。 堆栈表示已经捕获每个前缀之后的完全缩减状态，从而自动得出正确的最小长度。
