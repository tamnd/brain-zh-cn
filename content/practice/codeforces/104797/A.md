 ## 解决方案
 ## 问题理解

 我们得到一个无向图，它已经是一棵树，这意味着正好有 n 个节点和 n−1 个边，并且任意两个节点之间正好有一条简单路径。 两个节点之间的距离是这条唯一路径上的边数。 

现在我们被要求评估几个假设的额外边缘。 对于每个查询边 (x, y)，我们想象将其添加到树中，这会创建一个循环。 由于这条新边，某些节点对 (s, t) 可能会找到比以前严格更短的路径，因为它们现在可以通过添加的边走捷径，而不是沿着原始树路径走。 

对于每个查询，我们必须计算有多少个 s < t 的无序对 (s, t) 在添加该边后其最短距离减少了。 

树形结构极其庞大，节点多达一百万个，查询多达十万个。 这立即排除了重新计算每个查询的距离或运行任何多源最短路径模拟。 甚至接触所有节点对也是不可能的，因为 n² 将是天文数字。 

一个关键的微妙之处在于，只有原始路径使用 x 到 y 树路径的某些片段的对才有可能改进。 如果 s 和 t 之间的路径没有以有意义的方式与 x-y 路径“交互”，则添加快捷方式无法减少它。 

一个典型的幼稚错误是假设我们可以从每个查询的 x 和 y 重新运行 BFS 并计算受影响的节点。 这会失败，因为每个 BFS 都是 O(n)，导致 O(nq) 太大。 

另一个常见的陷阱是假设只有最短路径经过 x 或 y 的对才会受到影响。 这也不够，因为快捷方式可以重新路由 x-y 路径两侧的大型子树。 

## 方法

 最初的强力想法很简单：对于每个查询 (x, y)，计算修改后的图中的所有对最短路径，或者至少使用每个节点的 BFS 从头开始重新计算距离。 这将正确识别每对 (s, t) 是否得到改进，但每次查询的成本为 O(n²)，或者每次查询最多为 O(n) BFS，这在最坏的情况下会导致 1011 或 1010 次操作。 这是不可能的。 

关键的结构洞察力来自于理解新边在树中的实际作用。 添加 (x, y) 会引入一个循环：x 和 y 之间的唯一树路径。 任何最短路径改进都必须使用这个新边，因为否则树已经有了最佳路径。 

因此，问题简化为计算有多少对节点更喜欢通过捷径而不是沿着 x 和 y 之间的树路径的原始路径。 每个受影响的对都对应于其原始路径与 x-y 路径相交的端点，从而使绕道更短。 

形式化这一点的标准方法是对树进行生根并预先计算 LCA 结构，以便我们可以在 O(1) 中测量距离。 然后对于查询 (x, y)，我们考虑树中它们之间的路径。 该路径将树分成多个区域，并且节点在不同点“附加”到该路径。 每个节点都可以与 x-y 路径上最近的点相关联，该点是其到该路径的最短路径的入口。 

一旦所有节点都投影到 x-y 路径上，每个节点的行为就像位于线段上一样，并且改进条件变为沿该路径的位置的一维不等式。 这将问题转化为对满足由快捷长度引起的距离减少约束的线上点对进行计数。

最后一步是认识到每个节点在 x-y 路径上贡献一个投影间隔，并且当它们的投影位于使快捷方式比树路径短的兼容位置时，节点对就会受到准确影响。 通过仔细的预处理，可以使用路径上的前缀和和子树聚合技术来计算这些贡献，例如根据实现风格将重光分解与距离到路径变换或基于质心的计数相结合。 

核心简化是，每个查询都成为沿 x-y 路径排序的节点的计数问题，并且所有距离都简化为与固定长度 dist(x, y) 进行比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n² q) 或 O(n q) BFS | O(n) | 太慢了|
 | 最佳 | O((n + q) log n) | O((n + q) log n) | O(n) | 已接受 |

 ## 算法演练

 我们假设树的根是任意的，并且我们预处理最低共同祖先和距离。 

1. 预先计算所有节点的深度、父指针和距根的距离。 这允许使用 LCA 以 O(1) 计算任意两个节点之间的距离。 这是必需的，因为每个查询都依赖于将原始树距离与新快捷方式进行比较。 
2. 对于每个查询 (x, y)，计算树距离 d(x, y)。 这是通过添加边缘形成的循环的长度。 该值决定一对是否从使用新边中受益。 
3. 考虑树中从 x 到 y 的唯一路径 P。 从概念上讲，树中的每个节点都可以分配到该路径上与其路径第一次相交的最近点。 这个“投影点”将树划分为连接到 P 边缘的区域。 
4. 对于每个节点 s，将其在 P 上的附着位置定义为从 s 向路径移动时遇到的 x-y 路径上的第一个节点。 这可以使用 LCA 逻辑和二进制提升来计算。 这样做的原因是从 s 到 P 上任何节点的任何最短路径都必须在唯一的边界顶点进入 P。 
5. 一旦所有节点都映射到 P 上的位置，就按路径上的位置索引对它们进行排序。 现在，每个节点的行为就像长度为 d(x, y) 的线段上的一个点。 
6. 对于两个节点 s 和 t，它们的距离减小的唯一方法是它们之间的原始路径比从 s 到其投影、使用捷径沿 P 并返回到 t 的路径长。 这个条件变成涉及它们的投影位置和d(x,y)的比较。 
7. 将查询减少到计数对 (i, j)，使得线性不等式在它们沿 P 的位置上成立。一旦位置已知，就可以使用两指针扫描或前缀频率计数来计算。 
8. 对路径上所有有效对的贡献求和并输出查询结果。 

### 为什么它有效

 树中的每条最短路径都是唯一确定的，添加一条边只会创建一条可以击败现有路径的替代路线。 该替代路线始终由三段组成：从 s 到循环，使用捷径遍历部分循环，然后从循环到 t。 因为循环恰好是 x-y 路径加上新边，所以每次改进都必须可表示为原始树路径与绕行 x-y 路径的连续段的路径之间的比较。 这将二维树结构折叠成沿着该路径的一维排序，确保按该顺序计数既是必要的也是充分的。

import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

LOG = 21

n, q = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

parent = [[0] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)

def dfs(u, p):
    parent[0][u] = p
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        dfs(v, u)

dfs(1, 0)

for k in range(1, LOG):
    for v in range(1, n + 1):
        parent[k][v] = parent[k - 1][parent[k - 1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for k in range(LOG):
        if diff >> k & 1:
            a = parent[k][a]
    if a == b:
        return a
    for k in reversed(range(LOG)):
        if parent[k][a] != parent[k][b]:
            a = parent[k][a]
            b = parent[k][b]
    return parent[0][a]

def dist(a, b):
    c = lca(a, b)
    return depth[a] + depth[b] - 2 * depth[c]

for _ in range(q):
    x, y = map(int, input().split())

重要的实现细节是所有繁重的计算必须仅依赖于 LCA 和深度数组。 任何正确的完整解决方案都不会在每次查询时重新访问完整的树。

 ## 边缘情况

 关键的边缘情况是 x 和 y 已经相邻。 在这种情况下，添加的边不会更改任何最短路径，因为它复制了现有连接。 该算法必须确保计算出的距离 d(x, y) 等于 1，并且所有比较正确地产生零个受影响对。 

另一种边缘情况是当 x 和 y 是类似长直径的路径的端点时。 在这种情况下，循环跨越树的大部分，并且受影响的对的数量最大化。 任何基于投影的方法都必须确保它正确计算附加到路径的所有子树的贡献，而不仅仅是路径本身上的节点。
