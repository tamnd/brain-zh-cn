 ## 解决方案
 ## 问题理解

 我们得到一个仅由小写字母组成的长字符串以及对该字符串的子字符串的少量查询。 每个查询都关注字符串的连续段，并要求我们在该段内找到非常特定的模式。 

我们正在寻找的模式是该形式的重复`t + t`，表示一些非空子串`t`紧接着是一个与其自身相同的副本。 在所有完全包含在查询区间中的双倍子串中，我们想要最大可能长度的子串`t`。 换句话说，我们正在搜索前半部分等于后半部分的最长偶数长度子串，并且我们必须报告该半部分的长度以及它出现的最左边位置。 

如果查询范围内不存在此类重复，我们将返回长度零，并将起始索引定义为查询的左边界。 

字符串长度可以大到一百万，但是查询次数最多一百个。 这种不平衡是核心提示。 只要每个查询都能相对快速地得到回答，我们就可以对整个字符串进行大量的预处理。 任何接近对所有子字符串进行每次查询线性扫描的操作都已经太慢了，因为即使是对大段的单个查询也可能会花费$O(n^2)$在朴素的子串比较逻辑中。 

主要的困难在于，我们不仅要求重复的存在，而且要求最大长度，以及关系中最左边的出现次数。 该组合通常表示后缀数组、后缀自动机或具有范围检查的滚动哈希等结构。 

一种简单的方法是检查查询中每个可能的起始位置和每个可能的长度，比较子字符串。 当字符串重复时，即使在小例子上也会默默地失败。 例如，在像这样的字符串中`aaaaaa`，每个位置都会生成许多有效的重复，并且子串比较很快就会退化为二次或更糟糕的行为。 

另一个微妙的失败案例是重叠重复。 例如，在`ababab`，片段内的最佳重复可能比稍后出现的较短重复开始得更早。 在第一个有效对处停止的简单扫描将返回错误的位置。 

最后，边界处理很棘手。 重复`t+t`必须完全适合内部`[a, b]`。 一个常见的错误是只检查开始位置而不确保下半场保持在界内。 

## 方法

 直接的暴力解决方案将针对每个查询尝试每个可能的中心位置和每个可能的长度`len`，然后验证是否`s[i:i+len] == s[i+len:i+2len]`。 每次比较都是线性的`len`，所以即使我们通过哈希优化比较，我们最终仍然会检查$O(n^2)$最坏情况下每个查询对。 对于百万字符的字符串来说，这是完全不可行的。 

关键的观察结果是，可以使用滚动哈希或后缀数组 LCP 结构将子字符串的相等性简化为快速范围相等性检查。 一旦我们可以比较任意两个子字符串$O(1)$，问题就变成了对每个可能的起始位置的长度搜索。 

第二个结构观察是查询的数量非常少。 这允许我们对字符串上的全局数据结构进行一次预处理，然后通过仅扫描其间隔来独立地回答每个查询。 

我们预先计算字符串和基数幂的多项式滚动哈希。 这使我们能够在恒定时间内比较任何子字符串。 对于每个查询间隔，我们尝试候选起始位置，并使用二分搜索计算从那里开始的最长重复`t`。 重复条件变成了之间的哈希相等性检查`[i, i+len-1]`和`[i+len, i+2len-1]`。 

为了避免错过全局最大值，我们不会在第一个有效重复处停止。 相反，我们评估查询间隔内的所有有效起始位置，跟踪最佳长度和实现它的最小索引。 

这会将每个查询转变为间隔内的受控扫描，其中每次检查的重复长度都是对数的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$每个查询的最坏情况$O(1)$| 太慢了 |
 | 最优（散列+每个位置二分搜索）|$O(q \cdot n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们在字符串上构建滚动哈希，以便可以在恒定时间内计算任何子字符串哈希。 

对于每个查询，我们将自己限制在该段`[l, r]`。 我们想找一对`(i, len)`这样`i + 2*len - 1 ≤ r`并且重复条件成立。 

我们按如下方式进行。 

1. 预先计算整个字符串的前缀哈希值和基数幂。 

这允许恒定时间的子字符串哈希提取。 
2. 对于每个查询`[l, r]`, 初始化`best_len = 0`和`best_pos = l`。 
3. 迭代每个可能的起始索引`i`从`l`到`r`。 

我们只考虑`i`如果有至少重复长度 1 的空间，这意味着`i + 1 ≤ r`。 
4. 对于每个`i`，执行二分查找`len`从`0`到`(r - i + 1) // 2`。 

在每个中点，比较哈希值`s[i : i+len]`和`s[i+len : i+2*len]`。 
5. 如果哈希值匹配，则重复有效`len`，所以我们尝试扩展`len`向上； 否则，我们会减少它。 
6. 二分查找结束后，得到最大有效值`len`对于那个起始位置。 
7. 更新查询的全局答案：

 如果`len > best_len`, 替换两者`best_len`和`best_pos`;

 如果相等，保留较小的索引。 
8. 输出`(best_len, best_pos)`。 

### 为什么它有效

 该算法依赖于两个不变量。 首先，滚动哈希保证相等的子字符串始终产生相同的哈希值，因此在二分搜索期间不会错过任何有效的重复。 二、对于每个固定的起始索引`i`，二分查找从那里开始找到最大可能的重复长度，因为谓词“两半相等”是单调的，因为如果重复在长度上失败`len`，所有较大的长度也无法满足该固定起点。 

由于我们评估查询范围内的每个有效起始位置，因此每个可能的重复候选者都会以其最大形式被考虑一次，从而确保找到最佳的全局重复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_hash(s, base=91138233, mod=10**9+7):
    n = len(s)
    h = [0] * (n + 1)
    p = [1] * (n + 1)

    for i, c in enumerate(s):
        h[i + 1] = (h[i] * base + (ord(c) - 96)) % mod
        p[i + 1] = (p[i] * base) % mod

    return h, p

def get_hash(h, p, l, r, mod):
    return (h[r] - h[l] * p[r - l]) % mod

def solve():
    n, q = map(int, input().split())
    s = input().strip()

    mod = 10**9 + 7
    h, p = build_hash(s, mod=mod)

    def subhash(l, r):
        return (h[r] - h[l] * p[r - l]) % mod

    out = []

    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1

        best_len = 0
        best_pos = l

        for i in range(l, r + 1):
            hi = (r - i + 1) // 2
            lo = 0
            cur = 0

            while lo <= hi:
                mid = (lo + hi) // 2
                if mid == 0:
                    lo = 1
                    continue

                if i + 2 * mid <= r + 1:
                    if subhash(i, i + mid) == subhash(i + mid, i + 2 * mid):
                        cur = mid
                        lo = mid + 1
                    else:
                        hi = mid - 1
                else:
                    hi = mid - 1

            if cur > best_len:
                best_len = cur
                best_pos = i

        out.append(f"{best_len} {best_pos + 1}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案从前缀散列开始，以便任何子字符串比较都简化为对预先计算的值进行算术运算。 帮手`subhash`隔离提取子字符串哈希的逻辑，这对于保持查询循环的可读性和避免边界错误至关重要。 

在每个查询中，我们将索引转换为从零开始的形式并扫描每个可能的起始位置。 对于每次开始，我们都对最大有效重复长度进行二分搜索。 关键约束检查`i + 2 * mid <= r + 1`确保重复的子字符串不会溢出查询段，这是常见的差一错误源。 

结果跟踪首先对长度进行严格比较，然后对位置进行严格比较，保证保留最左边的最大值。

 ### 示例 1

我们检查每个起始位置。

 | 3 | 啊啊| 1 |

 最佳重复是从位置 3（基于 1 的位置 4）开始的长度 1，对应于`"aa"`里面`"aabaa"`。 

这证实了重叠和非重叠的候选者都被考虑在内，并且最左边的平局打破工作正常。

 ## 边缘情况

 一个重要的边缘情况是完全周期性的字符串，例如`aaaaaa`。 每个位置都会产生多个有效的重复，并且算法必须确保较长的重复优于较短的重复，即使它们开始较晚。 对所有位置的扫描保证`(len, pos)`是全局优化而不是局部贪婪。 

另一种情况是重叠重复，例如`ababab`。 在位置 1，有效长度包括 1 (`ab ab`), 2 (`abab abab`被截断），并且算法必须正确识别最大有效重复，而不会被重叠边界混淆。 条件`i + 2*len ≤ r`通过强制执行严格的非重叠结构来确保正确性。
