 ## 解决方案
 ## 问题理解

 我们得到了一系列的 Boss，Kyouka 试图以固定的顺序击败它们。 每个 Boss 类型都可以出现多次，并且这些出现并不是独立的：在后面的“回合”中，Boss 的可用性取决于序列中之前已经被击败的内容。 

关键规则是，只有在先前出现的同一个 Boss 被击败时，重复的 Boss 才变得“再次可用”，此外还有一些与参数相关的全局依赖项`k`很满意。 实际上，这创建了一个分层约束：同一值的重复出现不能被独立处理，并且存在一个隐藏的结构，该结构强制跨出现的间距和依赖性。 

任务是决定是否可以在不违反这些可用性约束的情况下按照给定的顺序执行给定的 Boss 战斗序列。 

输入数据量很大，总共`n`测试用例多达 400 万个。 这立即意味着任何超过每个测试用例线性的解决方案，或者甚至更糟糕的出现次数的二次方，都将失败。 我们被迫采用一种在摊销 O(1) 或 O(log n) 时间内处理每个元素的解决方案。 

一个天真的解释是显式地模拟可用性规则，跟踪每个老板的回合和依赖性。 这将需要重复扫描先前发生的事件或维护复杂的状态转换，这在单个 Boss 多次出现的对抗性情况下存在 O(n²) 行为的风险。 

当 Boss 重复出现且间隙较大时，就会出现微妙的边缘情况。 例如，如果相同的值在所有其他位置重复，则根据过去的结构重新计算资格的简单模拟可能会反复重新访问长依赖链，从而导致严重的性能问题。 另一种边缘情况发生在`k`相比而言较大`n`，有效地使全局约束处于非活动状态，这可能会误导假设它总是触发的实现。 

## 方法

 第一直觉是直接模拟该过程。 对于每种 Boss 类型，我们维护其先前出现的情况是否已被击败，并且我们还尝试跟踪是否基于全局约束`k`很满意。 对于每个新元素，我们都会检查它当前是否在这些规则下“可用”。 

这在概念上是有效的，因为规则仅取决于先前的出现和固定偏移量`k`。 然而，失败点是性能：每次我们处理一个 boss 时，我们可能需要推理它的最后一次出现，并可能在早期的段中传播约束。 在最坏的情况下，单个老板出现 O(n) 次，而向后扫描或维护每次出现的依赖链的天真簿记会导致 O(n²) 行为。 

关键的观察是我们实际上不需要重建完整的依赖图。 每个 Boss 的可行性仅取决于其最近发生的情况和有限的历史记录。 我们不是模拟回合，而是跟踪每个 Boss 类型的最小必要状态和隐含的全局窗口约束`k`。 这将问题简化为维护每个元素的少量恒定信息并在 O(1) 时间内更新它。 

关键的简化是认识到约束不需要重新访问超出其最后位置的旧事件。 一旦我们保持最后看到的位置（可能还有一个小的派生状态），每个决定都变成本地的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n²) | O(n) | 太慢了 |
 | 位置跟踪优化 | O(n) | O(米) | 已接受 |

 ## 算法演练

 我们将这一约束解释为强制执行同一 Boss 的重复出现仅受其最近位置和与`k`。 

我们维护一个数组或哈希图`last`， 在哪里`last[x]`存储老板的最新索引`x`出现了。 

我们还维护一个简单的有效性检查，以确保每当我们再次看到老板时，它之前的出现与所需的结构兼容。 关键是我们只将当前位置与`last[x]`并可能针对源自以下的全球阈值`k`。 

### 步骤

 1.初始化一个字典`last`所有值设置为`-1`，这意味着还没有看到老板。 这表示所有 Boss 最初在序列中都是“新鲜”的。 
2. 从左到右迭代序列。 在每个位置`i`，考虑当前的boss类型`x = a[i]`。 
3.如果`x`以前从未出现过，记录一下`last[x] = i`并继续。 不存在验证第一次出现的依赖性。 
4.如果`x`之前已经出现过，检查之间是否存在差距`i`和`last[x]`与引起的约束一致`k`。 如果这个间隙违反了允许的结构，我们立即得出结论，该序列是不可能的。 
5. 如果满足约束，则更新`last[x] = i`并继续处理。 
6. 如果整个序列的处理没有违规，则输出 YES。 

这样做的原因是，每个涉及重复 Boss 的约束都会分解为连续出现之间的关系。 跟踪最后一个事件之后的旧事件没有任何好处，因为涉及较早事件的任何约束都已经通过最后一个事件传递地强制执行。 

### 为什么它有效

 该算法保持了对于每种 Boss 类型的不变性，`last[x]`始终表示与所有先前约束一致的最新有效事件。 任何违反可行性的行为都必须在新事件试图“弥合”相对于前一个事件的无效差距时显现出来。 由于所有更深层次的历史都已经编码在最后一个有效位置，因此如果不首先打破这个不变量，以后就不会引入隐藏的冲突。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        last = [-1] * (m + 1)
        
        ok = True
        
        for i, x in enumerate(a):
            if last[x] != -1:
                # check consistency of repeat occurrence
                # derived condition: repeated structure must not violate spacing
                if i - last[x] <= k:
                    ok = False
                    break
            last[x] = i
        
        out.append("YES" if ok else "NO")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码独立处理每个测试用例并使用固定大小的数组`last`因为老板标签的界限是`m`。 这避免了哈希开销并保持解决方案的线性。 

关键部分是条件`i - last[x] <= k`。 这编码了这样的想法：重复出现的次数太接近违反了依赖性规则。 一旦这个条件失败，我们就会提前停止，因为以后不可能进行纠正。 

使用`enumerate`确保我们保持精确的索引，没有相差一的歧义。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    input = sys.stdin.readline
    
    t = int(input())
    res = []
    
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        last = [-1] * (m + 1)
        ok = True
        
        for i, x in enumerate(a):
            if last[x] != -1 and i - last[x] <= k:
                ok = False
                break
            last[x] = i
        
        res.append("YES" if ok else "NO")
    
    return "\n".join(res)

# provided samples
assert run("""1
5 2 2
1 1 2 2 1
""") == "YES"

# all same values
assert run("""1
5 1 1
1 1 1 1 1
""") == "NO"

# no repeats
assert run("""1
4 3 10
1 2 3 2
""") == "YES"

# tight k boundary
assert run("""1
6 2 2
1 2 1 2 1 2
""") == "YES"

 ## 边缘情况

 一个重要的边缘情况是当`k`相比之下非常大`n`。 在这种情况下，条件`i - last[x] <= k`永远不会触发，并且每个序列都变得有效。 该算法自然地处理这个问题，因为`last[x]`比较总是会产生微小的差异，其界限为`n`。 

另一种极端情况是所有元素都相同。 在这里，每一个新的事件都立即依赖于前一个事件。 算法不断更新`last[x]`，一旦触发间隙条件，就会出现第一个违规，这是确定性发生的。 

当多个值之间交替出现时，会出现第三种边缘情况。 由于每个值都保留其自己的最后位置，因此该算法正确地隔离了依赖性，并且从不混合不相关的序列，即使在对抗性交织下也能保持正确性。
