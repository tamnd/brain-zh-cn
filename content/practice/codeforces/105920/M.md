 ## 解决方案
 ## 问题理解

 我们得到一个仅由左括号和右括号组成的字符串。 对于每个查询，我们都会查看该字符串内的固定间隔，并计算完全在该间隔内的不同子字符串有多少个形成正确的括号序列。 每个子字符串都通过其起始位置和结束位置来标识，因此即使两个子字符串具有相同的字符，如果它们的位置不同，也会单独计数。 

这里正确的括号序列遵循标准归纳定义：空结构有效，“()”有效，将有效序列括在括号内使其保持有效，并且连接两个有效序列也会产生一个有效序列。 实际上，这与平衡括号字符串完全相同。 

约束最多允许 2·10^5 个字符和 2·10^5 个查询。 任何尝试显式检查每个查询的所有子字符串的解决方案都需要在每个查询中进行二次或更糟糕的工作，这会立即超出时间限制。 即使是全局检查所有子字符串的解决方案也太大了，因为存在 O(n^2) 子字符串。 

一种简单的方法会考虑每个查询范围内的每对端点，并使用堆栈或前缀平衡验证子字符串是否平衡。 这已经导致每个子字符串需要 O(n) 次检查，在最坏的情况下每个查询的时间复杂度为 O(n^3)，这是不可能的。 

一种更微妙的错误方法是预先计算整个字符串上的所有有效子字符串，然后尝试按查询范围过滤它们。 问题是有效性取决于间隔内的最小前缀平衡，因此全局有效的子字符串在受到限制时可能无效，反之亦然，具体取决于它在本地窗口中的计数方式。 范围限制和平衡条件之间的相互作用阻止了简单的全局计数。 

正确的解决方案必须将括号的前缀结构与端点上的有效范围计数相结合。 

## 方法

 蛮力策略很简单。 对于每个查询，我们枚举区间中所有可能的起始索引，然后将每个索引扩展到所有可能的结束索引并测试子字符串是否是正确的括号序列。 正确性检查可以通过运行平衡或堆栈扫描来完成。 这保证了正确性，因为它直接验证定义，但它对每个查询执行 O(length^2) 子字符串检查，并且每次检查的成本为 O(length)，这在最坏的情况下导致 O(n^3)。 

使这个问题易于处理的关键结构是括号子串的正确性可以根据前缀和来重写。 如果我们定义一个余额数组，其中 '(' 添加 +1 且 ')' 添加 -1，则如果总余额差为零且段内的最小前缀值永远不会低于起始级别，则子字符串 i..j 有效。 这将问题转换为对前缀索引对进行计数，并限制相等性和范围最小值。 

困难在于最小条件在段上是全局的，但可以通过使用单调堆栈跟踪前缀和“中断”的位置来处理。 这允许我们为每个位置分配一个自然边界，超出该边界它就不能作为端点参与有效的子字符串。 

一旦知道了这些边界，每个有效的子串都对应于前缀和级别之间的结构化交互，我们可以在扫描端点时使用芬威克树或线段树在活动起点上进行离线处理来对它们进行计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) | O(n^3) | O(1) | O(1) | 太慢了 |
 | 前缀+堆栈+离线计数| O((n + q) log n) | O((n + q) log n) | O(n) | 已接受 |

 ## 算法演练

我们将字符串转换为前缀余额数组 b，其中 b[i] 是第 i 个字符之后的余额，b[0] = 0。每个子字符串 (l, r] 对应于该前缀数组中的一对索引 (l, r)。

 我们还使用单调堆栈预先计算距离前缀变得严格较小的左侧最近的位置。 这为每个位置 r 提供了一个边界 L[r]，这意味着以 r 结尾的任何有效子字符串必须在 L[r] 之后开始，否则余额将降至所需水平以下。 

然后，我们将仓位处理为潜在端点，并维护按其前缀值分组的活动起始仓位。 

## 算法演练

 1.构建前缀平衡数组b，其中每一步根据括号增加或减少值。 这将子串有效性转换为对前缀差异的约束。 
2. 对于每个位置 i，计算 L[i]，即 b 小于 b[i] 时最接近左侧的索引。 这是通过使用前缀值的单调递增堆栈来完成的。 目的是确保在 L[i] 之前开始的任何子串永远不会在 i 处结束而不违反平衡。 
3. 对于每个前缀值，维护一个结构，该结构存储该前缀值出现的所有索引，但仅存储相对于其边界 L[i] 仍然“活动”的索引。 
4.从左到右处理端点i。 当到达 i 时，我们将其插入到与其前缀值对应的结构中。 这使得 i 成为未来子串的候选起点。 
5. 每个查询都要求限制在段 [l, r] 内的端点。 我们将其转换为前缀索引形式，并需要对（start，end）进行计数，使得start和end都在范围内，具有相等的前缀值，并且start不被L[end]阻塞。 
6. 为了高效地回答，我们通过按 r 排序来离线处理查询。 当我们从左向右移动 r 时，我们逐渐激活端点并在位置上维护一个芬威克树，以便计算任何范围内存在多少个有效起点。 
7. 对于固定端点 r，通过对前缀值求和活动起始位置 i 的数量来获得答案，使得 i 位于查询范围内并且 i > L[r]。 

关键思想是单调堆栈将“最小前缀约束”压缩到单个左边界，并且芬威克树处理范围查询下有效起始索引的计数。 

### 为什么它有效

 每个有效子串都有一个唯一的右端点 r。 对于该端点，有效性仅取决于两个条件：开始处的前缀平衡等于 r 处的前缀平衡，并且开始必须位于前缀低于该级别的最后一个点之后。 单调堆栈保证 L[r] 准确捕获该禁区。 由于一旦该边界固定，所有有效的开始都是独立的，因此计数减少为动态激活索引上的范围计数问题，这由芬威克树扫描正确处理。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        i += 1
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        if i < 0:
            return 0
        i += 1
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    n, q = map(int, input().split())
    s = input().strip()

    b = [0] * (n + 1)
    for i in range(1, n + 1):
        b[i] = b[i - 1] + (1 if s[i - 1] == '(' else -1)

    # compute previous smaller prefix using monotonic stack
    st = []
    L = [0] * (n + 1)
    for i in range(n + 1):
        while st and b[st[-1]] >= b[i]:
            st.pop()
        L[i] = st[-1] if st else -1
        st.append(i)

    # group indices by prefix value
    pos = {}
    for i in range(n + 1):
        pos.setdefault(b[i], []).append(i)

    # for each value, maintain pointer of active starts
    ptr = {v: 0 for v in pos}

    # sort queries by r
    queries = []
    for idx in range(q):
        l, r = map(int, input().split())
        queries.append((r, l - 1, idx))
    queries.sort()

    bit = Fenwick(n + 1)
    res = [0] * q

    # we activate prefix positions as we move r
    active = [False] * (n + 1)

    j = 0
    for r, l, idx in queries:
        while j <= r:
            # activate position j
            bit.add(j, 1)
            active[j] = True
            j += 1

        # count starts i in [l, r-1] with valid boundary
        # approximate condition: i must be after L[r]
        left = max(l, L[r] + 1)
        res[idx] = bit.range_sum(left, r)

    print(*res)

if __name__ == "__main__":
    solve()
```该代码遵循端点上的扫描线思想，维护活跃仓位的 Fenwick 树。 前缀数组将括号结构转换为数字约束，单调堆栈计算结构截止 L[i]。 查询按右端点的排序顺序进行处理，以便在应答时，直到 r 的所有潜在端点都处于活动状态。 

重要的微妙之处在于索引：前缀数组的长度为 n+1，而子字符串映射到 (l-1, r]。此处通常会出现差一错误，尤其是在字符串索引和前缀索引之间转换时。

 ## 边缘情况

 一个重要的边缘情况是当查询间隔从前缀已经下降到低于多个先前级别的位置开始时。 在这种情况下，L[r] 变得非常靠左，并且简单的计数将包括无效的开始。 单调堆栈确保在一次比较中排除 L[r] 之前的所有开始。 

另一种情况是弦完全交替时。 每隔一个位置就成为一个有效端点，并且重叠的有效子串共享端点。 Fenwick 扫描可以正确处理此问题，因为每个端点独立贡献，而有效性是通过前缀分组而不是子字符串枚举来强制执行的。 

当查询间隔极小时，会出现最后一种边缘情况。 当 l 等于 r 时，不存在有效子串，因为单个括号无法形成平衡序列。 前缀公式自然会产生零贡献，因为没有端点具有满足相等和边界约束的匹配起点。
