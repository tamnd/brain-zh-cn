 ## 解决方案
 ## 问题理解

 我们有一行`n`细胞，最初都是白色的。 我们有两个喷漆作业。 第一次操作油漆`a`连续的红色单元格，从任意位置开始`x`使得红色块完全适合该行。 第二次操作油漆`b`连续的蓝色单元格，从任意位置开始`y`，也被限制在行内。 如果一个单元格先涂成红色，然后涂成蓝色，那么它最终会变成蓝色。 两次操作之后，我们想知道最终的着色是否可能是对称的：对于每个单元格`i`，其颜色与位置处的单元格颜色匹配`n+1-i`。 

输入由多个测试用例组成，每个测试用例指定`n`,`a`， 和`b`。 如果存在选择，则输出为“YES”`x`和`y`产生对称的颜色，否则为“NO”。 

界限是巨大的：`n`最多可达 10^9 并且`t`最多 500。这立即排除了任何显式构造长度数组的解决方案`n`因为即使是单个测试用例也可能超出内存限制，并且迭代所有位置会太慢。 解决方案必须依赖算术推理而不是模拟。 

当块占据相对于极端的长度时，就会出现边缘情况`n`。 例如，如果`a`或者`b`等于`n`，这幅画覆盖了整行。 小值`a`或者`b`如果它们可以适当居中，则仍然可以允许对称。 如果放置不仔细，红色和蓝色的重叠加上蓝色优先于红色，可能会造成不对称。 例如，与`n = 3, a = 2, b = 1`，红色块覆盖了1-2个单元格，单个蓝色单元格只能覆盖一个单元格。 如果蓝色单元放在中间单元上，则对称是可能的。 如果放置在其他地方，它可能会破坏对称性。 

## 方法

 暴力方法会尝试尝试所有有效的位置`x`和`y`，模拟绘画，然后检查生成的数组是否对称。 为了`x`， 有`n-a+1`选项，并且对于`y`有`n-b+1`选项。 检查对称性需要`O(n)`。 因此，最坏情况下的操作计数是`(n-a+1)*(n-b+1)*O(n)`。 自从`n`可以是10^9，这是不可行的。 

关键的见解是对称性仅取决于长度`a`和`b`，不在实际位置上`x`和`y`。 如果红块长度`a`和蓝色块的长度`b`满足`a + b <= n + 1`，总是可以将红色和蓝色块对称地放置在中心周围。 如果蓝色块长于行的一半，则它会主导对称性，因为它会覆盖红色。 捕获使最终着色对称的能力的条件简化为检查是否`a + b <= n + 1`。 这是因为我们可以根据需要将红色块开始放置在靠近左端的位置，蓝色块开始放置在靠近右端的位置，并且由于蓝色覆盖红色而可以解决任何重叠。 如果`a + b > n + 1`，块太长而无法避免不对称，使得对称不可能。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O((n-a+1)*(n-b+1)*n) | O(n) | 太慢了 |
 | 最佳 | 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，读取整数`n`,`a`， 和`b`。 
3. 检查是否`a + b <= n + 1`。 此条件保证了红色和蓝色块可以以蓝色块不破坏对称性同时仍完全覆盖其预期长度的方式定位。 直观上看，总和`a+b`表示这些块占据的单元格总数；`n+1`考虑奇数和偶数长度行中的对称主元。 
4. 如果条件为真，则打印“YES”。 否则，打印“NO”。 

为什么它有效：不变的是如果`a + b <= n + 1`，我们总是可以定位从索引 1 开始的红色块和以索引结束的蓝色块`n`，确保左右镜像单元的颜色匹配，必要时蓝色覆盖红色。 如果`a + b > n + 1`，任何放置都会导致一侧比其镜子具有更多的蓝色或红色，从而破坏对称性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, a, b = map(int, input().split())
    if a + b <= n + 1:
        print("YES")
    else:
        print("NO")
```该解决方案使用快速 I/O 读取输入，因为最多可以有 500 个测试用例。 它评估每个测试用例的简单算术条件并立即打印结果。 无需构建数组，避免了大内存问题`n`。 代码的简单性还避免了索引中的差一错误，因为我们直接根据块长度进行推理。 

## 工作示例

 考虑`n = 5, a = 3, b = 1`。 总和`a + b = 4`和`n + 1 = 6`。 自从`4 <= 6`，答案是“是”。 我们可以将红色块放置在位置 2-4 处，将蓝色块放置在位置 3 处。该行是`[white, red, blue, red, white]`，蓝色覆盖红色后对称。 

为了`n = 7, a = 7, b = 4`，我们有`a + b = 11`和`n + 1 = 8`。 自从`11 > 8`，对称性是不可能的。 7 长度的红色块和 4 长度的蓝色块的任何放置都会导致左半部分和右半部分不相等。 该算法正确地返回“NO”。 

| 测试| n | 一个 | 乙| a+b | n+1 | 结果 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 5 | 3 | 1 | 4 | 6 | 是 |
 | 2 | 7 | 7 | 4 | 11 | 11 8 | 否 |

 这些痕迹显示了总和比较如何直接捕获对称放置的可行性。
