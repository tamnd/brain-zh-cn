 ## 解决方案
 ## 问题理解

 该任务围绕着重复对数字应用简单的转换并跟踪我们这样做时出现的信息进行。 给定一个初始整数，然后反复查看它的连续倍数：数字本身，然后是它的两倍，然后是它的三倍，依此类推。 每次查看倍数时，您都会检查其十进制表示形式并记录到目前为止出现的数字。 

这个过程会持续下去，直到从 0 到 9 的每个数字至少被看到一次，或者不可能达到该状态。 输出是在第一种情况下必须检查的最后一个数字，或者是当倍数序列从未引入所有数字时的特殊失败值。 

输入通常是一系列测试用例，每个测试用例包含一个起始编号。 对于每一个，您都可以独立模拟这一数字收集过程并报告停止点。 

从复杂性的角度来看，关键参数是在覆盖所有数字或得出失败结论之前可能需要检查多少倍数。 每个步骤都需要将数字转换为其十进制形式并扫描其数字。 如果数字很大或者收敛很慢，那么每一步执行繁重工作或低效重新计算数字状态的简单方法仍然可以，但如果以不必要的开销实现，它很容易退化为缓慢的模拟循环。 

当起始数字为零时，会出现微妙的边缘情况。 在这种情况下，每个倍数也为零，这意味着不会出现超过 0 的新数字。正确的输出是指定的失败结果。 例如，如果输入为 0，则正确答案是失败标记，因为永远无法观察到数字 1 到 9。 如果粗心的实现没有明确地解释这一点，最终可能会无限循环。 

当模拟中的数字变大时，就会出现另一种极端情况。 尽管理论过程很简单，但重复的字符串转换和数字跟踪必须保持高效，以避免开销主导运行时间。 

## 方法

 最直接的策略是准确模拟流程所描述的内容。 对于给定的起始数字，您可以迭代乘数 k = 1、2、3 等。 对于每个 k，计算 n × k，将其转换为字符串，并标记到目前为止在集合中看到的所有数字。 每次迭代后，检查该集合是否包含所有十个数字。 如果是，则返回当前倍数。 

这种强力方法是正确的，因为它从字面上反映了定义。 它仅在满足所需条件时停止，并且绝不会跳过任何可能导致缺失数字的倍数。 

这种方法的问题不是概念上的，而是时间上的。 在最坏的情况下，收敛可能需要多次迭代。 每次迭代都会执行一次乘法和一次数字扫描，因此如果停止时间较长，则数字运算的总数会随停止时间线性增长。 然而，在这个特定的问题设置中，停止时间实际上受到数字饱和的限制，并且暴力模拟就足够了。 

使该解决方案安全的关键观察是，除了跟踪数字覆盖范围外，没有任何隐藏结构可供利用。 除了简单的乘法之外，不需要进行算术优化，因为唯一重要的状态是出现了哪些数字。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(K·d) | O(1) | O(1) | 已接受 |
 | 最佳模拟（相同的想法，清晰的跟踪）| O(K·d) | O(1) | O(1) | 已接受 |

 这里 K 是直到终止为止检查的倍数数量，d 是当前倍数中的位数。 

## 算法演练

1. 读取测试用例的数量并独立处理每个起始值，因为数字收集过程不跨用例共享状态。 
2. 如果起始数字为零，则立即输出失败结果，因为每个倍数都保持为零并且不会出现新的数字。 这可以防止无限循环。 
3. 维护一个大小为 10 的布尔数组或位掩码，以跟踪到目前为止已看到的数字。 将其初始化为空。 
4. 从 1 开始向上迭代乘数 k，将当前值计算为 n × k。 每次迭代对应于检查序列中的下一个倍数。 
5. 将当前值转换为数字，并在跟踪结构中标记每个数字。 此步骤是从号码中提取信息的唯一位置。 
6. 更新数字组后，检查是否已观察到所有十个数字。 如果是，则输出当前值并停止处理该测试用例。 
7. 如果并非所有数字都出现，则继续执行下一个乘数。 

### 为什么它有效

 在每一步 k，算法都正确记录了从 n × 1 到 n × k 的倍数序列中出现的数字。 影响终止的唯一状态是数字集的完整性。 由于每次迭代都严格将 k 前进一位并检查相应的倍数，因此不会跳过或重复计算任何数字出现，从而影响正确性。 数字集第一次完整时恰好对应于最小的 k，使得所有数字都出现在序列中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input().strip())
    for _ in range(t):
        n = int(input().strip())

        if n == 0:
            print("INSOMNIA")
            continue

        seen = [False] * 10
        remaining = 10
        k = 0

        while remaining > 0:
            k += 1
            x = n * k

            while x > 0:
                d = x % 10
                if not seen[d]:
                    seen[d] = True
                    remaining -= 1
                x //= 10

        print(n * k)

if __name__ == "__main__":
    solve()
```该实现将数字跟踪保存在固定大小的布尔数组中，这避免了设置开销并使每个数字的更新时间恒定。 变量`remaining`避免重复扫描数组来检查完成情况，将停止条件变成简单的计数器检查。 

乘法循环增加`k`一步一步，确保我们按顺序探索倍数。 每个数字都使用模算术而不是字符串转换来分解，这减少了开销，并保持解决方案的效率，即使对于较大的中间值也是如此。 

的特殊处理`n == 0`是防止无限循环所必需的，因为除了 0 之外不能出现任何数字。

 ## 边缘情况

 用于输入`0`，算法立即触发特殊情况分支。 如果没有它，循环将重复计算零，仅标记数字 0 并且永远不会取得进展。 该防护确保在恒定时间内终止并产生正确的 INSOMNIA 输出。 

对于小的正数，例如`1`，仿真显示稳定的数字积累。 该循环多次运行，直到数字集完成，并且第一个完全覆盖恰好发生在 10 处，与预期的最小完成点匹配。 

对于像这样的数字`10`，第一次迭代已经引入了数字 1 和 0，后续迭代很快填充剩余的数字。 该算法自然地处理这个问题，因为数字集是单调的，一旦所有数字都存在，就会立即终止，无需额外计算。
