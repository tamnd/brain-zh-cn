 ## 解决方案
 ## 问题理解

 问题是关于一个过程，其中初始行的图块被重复转换为更大的序列，并且我们只能检查最终扩展序列中有限数量的位置。 从这些检查中，我们必须决定是否可以唯一地确定有关原始配置的某些内容，如果可能，则输出应检查哪些最终位置。 

从概念上讲，从一行 K 块开始。 每个图块都处于几种状态之一（在经典的分形设置中，金或银）。 然后使用固定规则将该行扩展 C 次：每个图块都被从先前配置派生的整个块替换，因此在 C 轮之后，最终长度变为 K^C。 我们没有得到最终的顺序。 相反，我们可以检查最终序列中的 S 位置。 每次检查都会返回最终扩展结构中恰好一个图块的状态。 

目标是选择最多 S 个检查位置，以便从它们的答案中我们可以重建有关原始 K 个图块的足够信息。 如果无法保证正确性，则输出必须反映这一点。 

驱动一切的关键约束是 K 和 C 足够大，以至于不可能显式构造最终序列。 即使 K = 100 和 C = 10 也已经给出了 100^10 个位置，这远远超出了任何计算。 这立即排除了任何模拟扩张的方法。 唯一可行的观点是将每个查询位置同时视为有关多个原始图块的编码信息。 

当 S 太小时，会出现微妙的边缘情况。 如果我们的检查次数少于我们必须消除歧义的原始图块的数量，那么任何策略都会失败。 例如，如果K = 5，C = 2，S = 2，则每个查询仅覆盖原始序列的有限投影，并且无法可靠地区分所有五个原始位置。 天真的贪婪方法可能仍然会选择两个位置，希望“覆盖”所有图块，但这会错过有关某些图块的信息，从而导致歧义。 

另一种边缘情况是当 K ≤ S 时。在这种情况下，通常可以将每个原始图块直接编码到单独的查询位置，但前提是我们正确映射扩展结构。 粗心的实现可能会错误地假设每个图块一个查询总是足够的，而不考虑 C 的压缩效果。 

## 方法

 思考问题的暴力方式是显式构造长度为 K^C 的最终序列，然后尝试向后推理：模拟与观察到的 S 位置一致的所有可能的原始配置，并检查原始状态是否可以唯一确定。 这种方法在概念上是简单且正确的，因为它准确地反映了转换。 然而，可能的原始配置的数量以 K 为指数，并且每个配置都会生成一个大小为 K^C 的序列，因此即使是第一个模拟步骤也几乎立即变得不可行。 操作数量激增，远远超出了任何现实的界限。 

关键的观察结果是，最终序列中的每个位置并不对应于单个原始图块，而是编码 C 个原始位置的结构化组合。 如果我们以 K 基表示形式解释最终索引，则每个数字对应于在扩展的一个级别上所做的选择。 这意味着通过仔细选择编码多个基本位置的索引，可以将单个查询设计为一次“覆盖”多个原始图块。

这导致将原始 K 个图块分组为大小为 C 的块。对于每个块，我们构造一个查询，其最终位置对整个原始索引块进行编码。 如果 K 不能被 C 整除，则最后一组在概念上是通过重复最后一个索引来填充的，这不会影响正确性，因为重复的索引不会在最终解码值中引入歧义。 

然后，我们将每个查询位置计算为由所选索引形成的基数 K 数。 因此，每个查询都是对原始配置空间的特定切片的确定性探测。 如果组数超过S，我们就无法涵盖所有​​必要的信息，所以答案是不可能的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(K^C · 2^K) | O(K^C·2^K) | O(K^C) | O(K^C) | 太慢了 |
 | 最佳| O(K) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们现在直接从扩展结构构建查询位置。 

1. 将 K 个原始图块分割成大小为 C 的连续组。每个组代表一个将被编码到一个查询中的压缩单元。 这种分组是自然的，因为每个最终位置都可以精确编码 C 个级别的选择。 
2. 对于每个组，通过将组解释为基数 K 数字，在最终序列中构建单个索引。 从 1 索引算术开始。 对于包含索引 a0、a1、...、a(C-1) 的组，将位置计算为 a0 * K^(C-1) + a1 * K^(C-2) + ... + a(C-1)。 这确保查询同时“触及”组中的所有图块。 
3. 如果一个组的元素少于 C 个（仅发生在末尾），则重复最后一个元素，直到达到长度 C。 这种填充不会扭曲信息，因为重复索引可以将构造的位置保持在同一表示等价类内。 
4. 收集所有构建的位置。 如果组数超过 S，则输出 IMPOSSIBLE，因为我们无法检查足够的位置来覆盖所有原始图块。 
5. 否则输出构建的位置。 

这样做的原因是每个构造的索引都唯一地编码扩展结构中完整组原始图块的状态。 Base-K 编码确保扩展的每个级别都独立地对最终位置做出贡献，因此两个不同的组不会折叠成相同的查询结果。 这保证了每个查询隔离原始配置空间的不相交部分，使得重建可行。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        K, C, S = map(int, input().split())

        # minimum number of checks needed
        need = (K + C - 1) // C

        if S < need:
            print("IMPOSSIBLE")
            continue

        res = []
        cur = 0

        while cur < K:
            x = 0
            for i in range(C):
                idx = min(cur, K - 1)
                x = x * K + idx
                cur += 1
            res.append(x + 1)

        print(*res)

if __name__ == "__main__":
    solve()
```该实现直接反映了分组逻辑。 变量`need`通过将 K 分成大小为 C 的块来计算需要多少个查询。如果 S 小于此值，我们立即拒绝。 

构建循环通过重复乘以 K 并添加当前索引来构建每个查询位置，从而有效地构建一个以 K 为基数的数字。 这`min(cur, K - 1)`当我们跑过组中的最后一个图块时处理填充，确保最终组保持有效。 

这`+1`最后从零开始的构造转换为用于输出位置所需的从一开始的索引。 

## 工作示例

 考虑一个小实例，其中 K = 5、C = 2、S = 3。 

我们将图块分组为 (0,1)、(2,3)、(4,4 填充)。 对于每个组，我们计算一个基数 K 数。 

| 步骤| 集团| 计算| 查询职位 |
 | --- | --- | --- | --- |
 | 1 | (0,1)| 0*5 + 1 | 0*5 + 1 2 |
 | 2 | (2,3) | 2*5 + 3 | 13 |
 | 3 | (4,4) | 4*5 + 4 | 25 | 25

 这会产生三个查询位置。 由于S = 3，我们可以直接输出它们。 

此跟踪显示了最后一组中填充的工作原理。 即使组不完整，重复 4 也可确保最终查询保持一致。 

现在考虑 K = 3、C = 3、S = 1。 

| 步骤| 集团| 计算| 查询职位 |
 | --- | --- | --- | --- |
 | 1 | (0,1,2) | (0,1,2) | 0_3^2 + 1_3 + 2 | 5 |

 我们生成一个查询，这已经足够了，因为 C 可以在一次检查中覆盖所有图块。 

这证明了 C 的压缩效果：当 C ≥ K 时，单个查询可以对整个原始数组进行编码。

 ## 边缘情况

 一种边缘情况是当 K = 1 时。该算法立即生成单个组，并且计算的索引始终为 1，无论 C 或 S。分组循环自然地处理此问题，因为`cur`从 0 开始，只需要迭代一次。 

另一种边缘情况是当 C ≥ K 时。在这种情况下，所有图块都被覆盖在一个组中，并且填充填充其余部分。 例如，K = 4, C = 10 会生成一个编码 (0,1,2,3,3,3,...) 的查询。 重复不会改变结构，因为所有额外的数字都映射到相同的最终分支，因此编码索引仍然有效。 

第三种边缘情况是 S 恰好等于所需的组数。 该算法恰好生成 S 个查询，并且不会发生提前终止。 每个组都是独立的，因此不存在重叠或缺失覆盖的风险。
