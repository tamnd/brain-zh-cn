 ## 解决方案
 ## 问题理解

 我们被要求构造固定长度的特殊二进制字符串，其中每个字符串代表多个基数的数字，并且所有这些解释的数字必须是复合的。 除了每个字符串之外，我们还需要为每个基本解释提供一个非平凡除数，以证明它们都不是素数。 

具体来说，每个候选都是长度为N的位串。第一个和最后一个字符固定为1，中间位可以变化。 对于每个这样的字符串，我们将其解释为以 2 到 10 为基数的数字。对于每个基数，所得整数不得为素数，并且我们必须为每个基数输出至少一个除数。 

输出不是单个答案，而是 J 个这样的有效字符串的集合，每个字符串与 9 个除数配对，每个基数从 2 到 10。 

尽管涉及的数字随 N 呈指数增长，但关键约束是 N 足够小，以便我们可以合理地搜索候选位串并使用确定性算术或模块化推理来验证它们。 

当尝试将完整的二进制字符串直接转换为高基数的整数而不处理溢出或不使用增量计算时，就会发生幼稚的解释错误。 例如，如果 N 约为 32，则在 Python 中直接转换就可以了，但在更严格的语言中，这会溢出并默默地破坏素数检查。 另一个微妙的边缘情况是假设在基数 2 中找到除数意味着有关其他基数的任何信息，这是错误的，因为更改基数会完全改变数字。 

## 方法

 暴力破解的想法很简单：枚举长度为 N 且端点为 1 的所有二进制字符串，以基数 2 到 10 解释每个候选值，并测试每个结果数字是否为合数。 对于每个碱基，我们尝试通过试除法找到一个达到一定限制的除数。 

这种方法是正确的，因为它在不依赖结构的情况下显式验证每个候选者的条件。 然而，搜索空间是 2^(N-2)，对于中等的 N，搜索空间增长得非常快。 即使对于 N = 32，我们也已经研究了超过 1600 万个候选，并且对于每个候选，我们执行九次基本转换加上重复的整除性检查，这很快就变得不可行。 

使问题易于处理的关键观察是我们不需要穷举搜索或完全分解大量数字。 我们只需要为每个基本表示展示一个小的非平凡除数。 这使我们能够使用启发式或有界因子搜索，通常使用预先计算的小素数或高达固定阈值的确定性试除法。 由于随机合数很可能有一个小因子或至少有一个低于适度界限的因子，因此我们可以通过拒绝那些无法在任何基数中快速产生除数的那些来积极修剪候选数。 

这将问题从完全素性测试转变为具有快速认证的受控搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举+全面检查| O(2^N·N·B) | O(2^N·N·B) | O(1) | O(1) | 太慢了 |
 | 候选生成+有界因子搜索 | O(K·N·B·sqrt(M)) | O(K·N·B·sqrt(M)) | O(1) | O(1) | 已接受 |

 这里 B = 9 个碱基，K 是所需的有效输出数。 

## 算法演练

1. 通过将第一位和最后一位设置为 1 来修复每个候选字符串的外部结构，因为有效的解决方案必须满足此约束，并且它将搜索空间从 2^N 减少到 2^(N-2)。 
2. 将剩余的 N-2 位作为二进制计数器进行迭代，以升序生成候选字符串。 这种系统枚举确保我们不会错过任何可能的配置。 
3. 对于每个候选字符串，通过增量评估值而不是每次都转换完整字符串，以 2 到 10 为基数对其进行解释。 这避免了重复昂贵的字符串到整数转换。 
4. 对于每个基本解释，尝试使用预先计算的素数列表通过试除法或通过检查不超过固定界限（例如 10^4）的整数来找到一个小除数。 目标不是完全分解，而只是找到复合性的见证。 
5. 如果任何碱基未能在允许的范围内产生除数，则立即丢弃该候选碱基。 尽早拒绝是至关重要的，因为它可以防止将时间花在毫无希望的事情上。 
6. 如果所有九个基都产生有效的除数，则将候选字符串与其除数一起存储，并继续，直到我们收集 J 个有效结果。 

这一程序的正确性取决于以下事实：每个被接受的候选者都在所有基地中得到明确认证，而每个被拒绝的候选者在同一规则下至少在一个基地中未通过认证。 

### 为什么它有效

 该算法保持这样的不变性：每个存储的字符串都伴随着 2 到 10 的每个基数的有效非平凡除数。由于每个除数都通过模除法显式验证，因此每个报告的数字都保证是合数。 搜索空间对于所有候选者都是详尽的，因此如果在探索的领域内存在解决方案，它最终会被发现。 早期剪枝只会删除无效的候选者，而不会丢弃有效的候选者，因为有效性纯粹是由我们直接测试的除数的存在来定义的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def to_base_value(bits, base):
    val = 0
    for b in bits:
        val = val * base + int(b)
    return val

def find_divisor(x):
    if x % 2 == 0:
        return 2
    d = 3
    while d * d <= x and d < 10000:
        if x % d == 0:
            return d
        d += 2
    return None

def solve():
    T = int(input())
    for _ in range(T):
        N, J = map(int, input().split())
        found = 0

        print("Case #{}:".format(_ + 1))

        candidate = (1 << (N - 1)) | 1

        for mask in range(1 << (N - 2)):
            if found == J:
                break

            bits = ['1']
            for i in range(N - 2):
                bits.append(str((mask >> i) & 1))
            bits.append('1')

            divisors = []
            ok = True

            for base in range(2, 11):
                val = to_base_value(bits, base)
                d = find_divisor(val)
                if d is None:
                    ok = False
                    break
                divisors.append(d)

            if ok:
                print("".join(bits), *divisors)
                found += 1

solve()
```实现的核心是使用位掩码直接构造候选位串，这保证了系统枚举。 每个候选者都会立即在所有碱基上得到验证，如果任何碱基未能产生小除数，我们就会尽早放弃它。 

基数转换以流式传输方式实现，在每一步将累积值乘以基数，从而避免构建大型中间表示。 除数搜索被故意限制，因为我们只需要一个见证，而不是完全分解。 

一个微妙的实现细节是基本循环内的提前退出。 如果没有它，一旦检测到单个故障，我们就会浪费时间计算不相关的基数的除数。

 ## 边缘情况

 One edge case is the smallest possible length, where the only valid candidate is all ones. For N = 2, the string 11 is always selected. In base 2 it evaluates to 3, which is composite only in the trivial sense of having no smaller valid representation in this constrained space, and the divisor search immediately finds 3 as a witness in relaxed implementations or accepts it as edge-defined valid output.

 Another edge case is when the search space is exhausted before finding J valid strings. In that situation, the algorithm relies on the fact that the problem guarantees existence within the explored domain, so termination without J results indicates an implementation bug rather than a mathematical failure.

 A final edge case occurs when the divisor bound is too small. If we cap trial division too aggressively, we may incorrectly reject valid candidates whose smallest factor exceeds the threshold, so the bound must be chosen carefully to balance speed and completeness within constraints.
