 ## 解决方案
 ## 问题理解

 我们正在处理一个过程，其中初始长度模式$K$通过确定性规则重复扩展$C$阶段，产生一个非常大的最终序列。 最终序列中的每个位置最终取决于原始模式中的一小部分位置窗口，但精确的映射是结构化的而不是随机的。 

扩建完成后，我们只允许检查$S$最终序列中的位置。 每次检查都会揭示完全扩展的结构的一个特征。 任务是选择那些$S$位置，以便从观察到的字符我们可以推断某些原始位置是否一定包含特定的配置。 在这个问题族的经典解释中，目标是确定最终扩展字符串中的一组索引，以便检查它们足以唯一地解决原始模式的不确定性，或者报告无法通过给定数量的检查来完成。 

核心难点是扩张呈指数级增长$C$，使得最终的字符串无法显式构造。 每个最终位置都编码来自多个原始位置的混合贡献，并且这种编码的结构允许我们将许多原始索引“压缩”到单个查询中。 

从约束的角度来看，重要的含义是$K$可以足够大，任何二次甚至$O(KC)$模拟完全扩张是不可能的。 唯一可行的解​​决方案必须直接对扩展规则的结构进行操作。 自从$C$也可以很大，任何迭代每个位置的所有扩展级别的方法都必须仍然保持线性$K$最坏的情况是。 

不明显的失败案例来自于对单个查询位置携带多少信息的误解。 

第一个边缘情况发生在$S \cdot C < K$。 在这种情况下，允许的支票中没有足够的“自由度”来涵盖所有原始职位，因此答案是不可能的。 例如，如果$K = 5$,$C = 2$， 和$S = 2$，我们至少需要$\lceil 5/2 \rceil = 3$检查，因此即使简单的方法仍可能尝试输出一些索引，正确的输出也是不可能的。 

当出现第二种边缘情况时$K = 1$。 扩展变得微不足道，因为最终的字符串仅取决于以结构化方式重复的单个原始位置。 任何有效的解决方案都必须立即返回单个查询，无论$C$和$S$。 粗心的分组方法可能会使情况变得过于复杂，并产生不必要的甚至无效的索引。 

## 方法

 暴力破解的想法是明确地模拟扩张过程。 从原字符串长度开始$K$，我们重复应用变换规则$C$次构造最终字符串。 一旦构建了完整的扩展序列，我们将检查每一个可能的集合$S$位置并检查它们是否唯一确定原始配置。 

这种方法原则上是正确的，因为它直接遵循流程的定义。 问题在于规模。 如果展开式将长度乘以$K$在每一步中，最终的字符串都有大小$K^C$。 即使对于中等值，例如$K = 10$和$C = 5$，这已经达到$10^5$，更大的约束很快就变得不可行。 枚举所有可能的查询集会在此基础上添加额外的组合爆炸。 

关键的结构观察是每个最终位置编码一个碱基$K$通过扩展树的路径。 我们可以将每个最终索引视为基数中的数字，而不是考虑字符串$K$，其中每个数字对应于在一个扩展级别上所做的选择。 这意味着单个查询位置实际上代表了以下内容的压缩视图$C$原始指数。 

由于这种结构，我们不需要探索完整的扩展字符串。 每个查询都可以构建为聚合来自最多一组的信息$C$原来的职位。 通过将原始索引分组为大小的块$C$，并将每个块编码为单个基$K$位置，我们可以仅使用覆盖整个原始序列$\lceil K / C \rceil$查询。 

因此，最佳解决方案是直接构造这些编码索引，而不是对扩展进行任何模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟|$O(K^C)$|$O(K^C)$| 太慢了 |
 | Base-K 组编码 |$O(K)$|$O(1)$| 已接受 |

 ## 算法演练

 我们通过将原始索引块视为基数中的数字来构建答案$K$。 

1.从原始序列的第一个位置开始，按size的块进行处理$C$。 每个块将对应于最终答案中的一个查询。 
2. 对于每个块，将其元素解释为基数中的数字$K$数字。 如果块的数量少于$C$元素，将缺失的位置视为中性数字$0$。 此填充确保每个查询对应于扩展树中的有效路径。 
3.转换基数-$K$数字到最终扩展字符串中的 1 索引位置。 这是通过将累积值重复乘以来完成的$K$并添加当前数字。 
4. 将此计算出的位置附加到查询列表中。 
5. 如果 chunk 数量超过$S$，输出不可能，因为我们无法承担足够的检查来覆盖所有原始位置。 

这种分组起作用的原因是，每个查询通过利用扩展路径如何编码跨级别的选择组合，有效地将多个原始索引“捆绑”到单个检查中。 

### 为什么它有效

 扩展过程形成一个完整的$K$- 深度二叉树$C$，其中每个叶子对应于最终位置。 任何叶子都由一系列的唯一标识$C$选择，每个都在范围内$[0, K-1]$。 因此，单个查询可以解释为选择一个叶子，通过将多个原始位置嵌入到该序列中来对它们进行编码。 由于在这种编码中每个原始位置都可以精确地映射到一位数字位置，因此对它们进行分组不会丢失信息。 构建的索引确保每个原始位置至少影响一个查询结果，从而保持可区分性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    K, C, S = map(int, input().split())

    # Minimum number of checks needed
    need = (K + C - 1) // C
    if S < need:
        print("IMPOSSIBLE")
        return

    res = []
    idx = 0

    while idx < K:
        val = 0
        for i in range(C):
            pos = min(idx, K - 1)
            val = val * K + pos
            idx += 1
        res.append(val + 1)

    print(*res)

if __name__ == "__main__":
    solve()
```实施直接遵循分组策略。 变量`idx`跟踪我们接下来要编码的原始位置。 每个查询都是通过累积最多来构建的`C`位置进入基地-$K$号码存储在`val`。 乘以`K`移动前面的数字，同时添加`pos`附加下一个数字。 

使用无减法处理边界`min(idx, K - 1)`确保使用最后一个有效索引安全地填充不完整的最终组。 这可以避免超出范围的行为，同时保持正确性，因为填充不会影响编码方案中的可区分性。 

决赛`+1`从内部使用的从零开始的索引转换为所需的从一开始的输出格式。 

## 工作示例

 考虑$K = 5$,$C = 2$,$S = 3$。 

我们处理指数$[0,1,2,3,4]$2人一组。 

| 块| 计算| 价值|
 | --- | --- | --- |
 | (0,1)|$0 \cdot 5 + 0 = 0$， 然后$0 \cdot 5 + 1 = 1$| 1 |
 | (2,3) |$0 \cdot 5 + 2 = 2$， 然后$2 \cdot 5 + 3 = 13$| 13 |
 | (4,4) | 填充组：$0 \cdot 5 + 4 = 4$， 然后$4 \cdot 5 + 4 = 24$| 24 |

 输出是$2, 14, 25$转换为基于 1 的索引后。 

此跟踪显示每个查询如何将两个原始位置压缩到扩展空间中的单个索引中。 

现在考虑$K = 3$,$C = 2$,$S = 2$。 

| 块| 计算| 价值|
 | --- | --- | --- |
 | (0,1)|$0 \cdot 3 + 0 = 0$,$0 \cdot 3 + 1 = 1$| 1 |
 | (2,2) | 填充：$0 \cdot 3 + 2 = 2$,$2 \cdot 3 + 2 = 8$| 8 |

 输出是$2, 9$。 

这证实了通过填充正确处理不完整的最终组。

 ## 边缘情况

 对于$K = 1$，算法立即生成单个查询。 循环运行一次，对长度为单位的数字序列进行编码$C$，但由于所有数字实际上为零，因此输出折叠到位置$1$。 扩展结构并不重要，因为所有路径都收敛到相同的原始索引。 

对于以下情况$S < \lceil K/C \rceil$，在尝试任何构造之前，算法会正确地以 IMPOSSIBLE 提前终止。 这可以防止产生会错误地表明可行性的部分覆盖。 

对于不完整的最终组，填充可确保最后的编码值仍然形成有效的基数$K$数字。 执行仍然会产生一个明确定义的查询，因为重复乘以$K$吸收填充而不破坏位置编码。
