 ## 解决方案
 ## 问题理解

 我们给定一个长度序列$k$，其中每个元素$a_i$是一个非负整数，边界为$m$。 对于任何此类序列，其值定义为所有对的总和，其中第二个索引不超过该对的按位异或的第一个索引：$$\sum_{i=1}^{k} \sum_{j=1}^{i} (a_i \oplus a_j).$$这意味着每个元素都与其自身以及所有先前的元素进行异或，并且所有这些异或值都累积到单个整数分数中。 任务是计算有多少序列准确地产生目标分数$n$，所有值均取模$10^9+7$。 

关键的困难在于该函数通过成对的异或交互来耦合所有位置。 尽管元素是单独有界的，但分数取决于它们之间的全局交互，因此每个索引的局部推理是不够的。 

约束的长度较小，但取值范围较大。 和$k \le 18$，我们负担不起任何指数级的东西$m$，但呈指数增长$k$仍然可行。 价值观$m$上升到$10^{12}$，因此按位处理数字是强制性的。 目标$n$上升到$10^{15}$，这也强烈表明按位分解。 

一个天真的尝试会尝试生成所有$(m+1)^k$序列，计算异或对和，并计数匹配。 这立即是不可行的，因为即使对于中等程度的$m$，这会爆炸。 甚至减少$m$对于小情况，计算每个序列的双和是$O(k^2)$，这已经太慢了。 

更微妙的失败来自于试图独立地处理每个比特的贡献，而不仔细处理进位或交互结构。 XOR 本身是按位独立的，但双和以非平凡的组合方式耦合跨位置的位的出现。 

一个具体的边缘陷阱是假设一个位的贡献仅取决于有多少个数字设置了该位。 虽然部分正确，但必须仔细推导； 否则，由于引入的排序限制，具有相同计数但不同排序的序列将被错误计数$k$。 

## 方法

 第一个自然的想法是对所有序列进行暴力破解。 对于每个序列，我们计算所有成对 XOR 贡献并检查总和是否等于$n$。 这在概念上可行，但需要枚举$(m+1)^k$州。 和$m$最多$10^{12}$，这是不可能的。 

即使我们忽略了影响的大小$m$想象它很小，计算价值仍然需要成本$O(k^2)$，因此总数变为$O((m+1)^k \cdot k^2)$，它立即超出极限。 

一旦我们观察到 XOR 是按位独立的，问题的结构就变得可用。 总值是位的总和，每个位根据其在位置对中出现的次数独立贡献。 这将数字大小分开$m$转化为按位限制问题，并将成对异或和转化为位贡献的组合计数。 

一旦我们转向位DP，每个数字都是在约束下一点一点构造出来的$a_i \le m$。 关键的见解是，我们只需要跟踪每个位中有多少个元素为 1，以及这些位对成对 XOR 计数的贡献。 这将问题简化为比特上的数字 DP 与序列位置上的 DP 相结合。 

最终的归约是一个迭代的 DP$m$，在紧界下构建有效序列，并同时跟踪异或对贡献如何累积到$n$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O((m+1)^k \cdot k^2)$|$O(k)$| 太慢了|
 | 位置和位上的按位 DP |$O(k \cdot \text{bits} \cdot states)$|$O(states)$| 已接受 |

 ## 算法演练

 核心思想是从最高有效位向下逐位处理数字，同时保持关于序列如何形成以及到目前为止已累积多少异或贡献的 DP。 

我们定义一个 DP 状态来跟踪我们已经处理了多少元素，以及我们是否仍然紧绷$m$，以及对 XOR 的累积贡献总计到当前位。 

1. 我们处理一些$m$从最高的（大约 40 以来）$m \le 10^{12}$）下降到 0。这确保了当我们决定一些$a_i$，我们尊重约束$a_i \le m$按字典顺序以二进制形式。 
2. 对于每个序列位置，我们一一分配位。 在给定的位，每个$a_i$有一个二元选择，但是如果我们仍然匹配前缀，则该选择受到限制$m$。 这是多个并行数字的标准数字 DP 结构。 
3. 对于每个 DP 状态，我们维护当前位为 1 的元素的数量。 如果在给定的位有$c$其中的$k$元素，那么该位对 XOR 和的贡献正好为$c \cdot (k-c+1)$类结构取决于包含自对。 正确的贡献来自对 XOR 引起的无序贡献的计数，并且这是增量计算的。 
4. 我们在降低位时同时保持累积的 XOR 和，将先前的贡献移动一位（乘以 2）并添加当前位的贡献。 
5. 我们还跟踪构造的前缀是否仍然等于$m$（严格约束），它决定了我们是可以自由分配位还是被迫分配位。 

处理完所有位后，我们对 DP 状态进行计数，其中累加值等于$n$。 

### 为什么它有效

 正确性来自于两次分离。 首先，XOR 是按位独立的，因此除了位置权重之外，每个位都独立地对最终数值做出贡献。 其次，字典数字 DP over 位确保所有构造的数字保持在界限内$m$。 在每一位上，对最终总和的所有贡献完全由 0 和 1 之间的分布决定。$k$位置，因此除了已经通过乘以 2 处理的移位之外，不存在隐藏的跨位依赖性。这使得 DP 既完整又不会过度计数，因为每个有效序列都恰好对应于通过 DP 状态的一条路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m, k = map(int, input().split())

    MAXB = 60

    # dp[tight][mask of k bits] -> we compress by count of ones at each bit step
    # Since k <= 18, we track counts of how many numbers have current bit = 1
    # dp[tight][c][value]
    
    from collections import defaultdict

    dp = [defaultdict(int), defaultdict(int)]
    dp[1][(0, 0)] = 1  # (ones_count, value)

    for b in reversed(range(MAXB)):
        ndp = [defaultdict(int), defaultdict(int)]
        mb = (m >> b) & 1

        for tight in (0, 1):
            for (ones, val), ways in dp[tight].items():
                for assign in range(1 << k):
                    if tight and assign > mb:
                        continue

                    cnt1 = bin(assign).count("1")

                    # contribution of this bit to XOR sum
                    # pairs with XOR = 1 are cnt1 * (k - cnt1)
                    contrib = cnt1 * (k - cnt1)
                    new_val = (val << 1) + contrib

                    ntight = tight and (assign == mb)
                    ndp[ntight][(cnt1, new_val)] = (ndp[ntight][(cnt1, new_val)] + ways) % MOD

        dp = ndp

    ans = 0
    for tight in (0, 1):
        for (ones, val), ways in dp[tight].items():
            if val == n:
                ans = (ans + ways) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```该实现同时遵循所有数字的二进制表示的位DP。 每个 DP 层对应于所有 DP 层中的固定一位位置$k$元素。 

这`tight`标志强制构造的数量不超过$m$。 每个状态还跟踪当前位中有多少元素为 1 以及迄今为止累积的 XOR 贡献。 该转换枚举了所有位分配$k$位置，这是可行的，因为$k \le 18$，所以至多$2^{18}$模式是存在的。 

一位的 XOR 贡献仅取决于选择了多少个，因为每一对不同的位在该位置恰好贡献一个 XOR，给出$cnt1 \cdot (k - cnt1)$。 

累加值在每一步都会向左移动，因为我们从高位移动到低位，从而有效地构建了最终的整数。

 输入：```

```这里$k=5$，因此每个位的分配最多涉及 32 个掩码。 DP 探索所有有效的位模式$m=6$并汇总 XOR 贡献。 

最终计数累加按位异或对和等于 30 的所有配置，表明 0 和 1 跨位置的多个分布可以产生相同的最终值。

 ## 边缘情况

 一种边缘情况是所有元素都相同，例如$k=3$,$m=2$， 顺序$[1,1,1]$。 在这种情况下，每个 XOR 都为零，因此总值为零。 DP 正确地计算了一次，因为所有位分配在各个位置上都是相同的，并且在每个位上产生零贡献。 

另一个边缘情况是当$m$是二减一的幂，例如$m=7$。 这里允许每个位模式最多 3 位，因此除了顶层之外，紧密标志永远不会成为限制性的。 DP 探索所有组合，最终的 XOR 贡献完全取决于状态准确捕获的每比特的组合分布。 

第三种边缘情况是$n=0$。 这对应于每个位级贡献相互抵消的所有配置，每当序列中的每个位都全零或全1时就会发生这种情况。 DP 自然地包括两种极端配置并正确计算它们，因为当贡献消失时$cnt1 \in \{0, k\}$。
