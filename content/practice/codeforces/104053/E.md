 ## 解决方案
 ## 问题理解

 我们有几部电梯，每部都从 1 楼开始，但不同时。 每部电梯都以每秒一层的匀速向上运动，所以一旦在某个时间启动$x_i$，到达楼层$f$正好在时间$x_i + (f-1)$如果没有什么干扰的话。 

不同的是，除了底部和顶部之外，每一层都有一个特殊的按钮。 如果在比赛开始前按下按钮，则到达该楼层的第一部电梯将被迫再等待一秒钟。 如果多部电梯同时到达，则索引最小的电梯被视为第一部电梯。 关键限制是所有按钮的按下都必须在比赛开始前决定。 

任务是确定对于每部电梯$i$，电梯启动时必须按下的最少按钮数量$i$成为第一个到达顶楼的人。 如果无法实现，我们输出$-1$。 

约束条件非常大，最多可达$5 \cdot 10^5$电梯和楼层数最多$10^9$。 这立即排除了任何逐层模拟运动或明确模拟每个按钮交互的方法。 任何有效的解决方案都必须将问题简化为推理到达时间的相对顺序，而不是模拟过程。 

一个微妙但关键的边缘情况来自“首次到达楼层”的行为方式。 由于每部电梯以相同的速度运行，因此每层电梯的相对顺序仅由其启动时间决定。 如果电梯$a$比电梯早启动$b$， 然后$a$更早到达每个楼层，这意味着它总是第一个触发任何楼层的任何按钮效果。 这意味着每个楼层的交互不能以简单的方式独立控制。 

一个天真的误解是假设我们可以自由地在不同的电梯之间分配延迟。 例如，人们可能认为我们可以按下不同的楼层按钮来有选择地减慢不同竞争对手的速度。 然而，由于同一个电梯总是在任何地方都是第一个（给定固定速度），所以所有按钮效果都会崩溃到那个最快的电梯上，使系统远不如最初出现的那样灵活。 

## 方法

 暴力方法会尝试逐层模拟比赛。 在每个楼层，我们将计算哪部电梯首先到达，如果按下按钮则应用延迟，然后继续向上。 由于楼层数最多可达$10^9$，这是完全不可行的。 即使我们只模拟相关事件，每次按下按钮都可能会改变未来的顺序，从而导致级联依赖关系仍然变得太大而无法处理。 

关键的观察结果是，由于所有电梯以相同的速度移动，因此每层楼的到达顺序与其启动时间的顺序相同。 这将整个动态过程分解为静态排序问题：最早启动的同一个电梯将始终是每个楼层的第一个电梯，包括所有按钮触发的交互。 

这会产生严重的后果。 由于只有每个楼层最先到达的电梯可以延迟，并且该电梯的身份在不同楼层之间不会改变，因此所有按钮按下只能影响全局最早启动的电梯。 再多的预处理也无法将延误重定向到其他电梯。 

因此，问题就简化为检查电梯是否$i$已经是全球最早启动的电梯。 如果是的话，它自然会是每个楼层的第一个，包括顶层，所以不需要任何按钮。 如果不是，则无法改变系统以使其超越真正最早的电梯，因为所有延迟只能应用于同一台主导电梯。

 ## 算法演练

 1. 计算所有电梯的最短启动时间。 这标识了在任何按钮按下配置下始终首先到达每个楼层的电梯。 
2、比较电梯启动时间$i$与这个最小值。 如果$x_i$严格大于最小值，则电梯$i$在初始排序中，它从来都不是任何楼层的第一层，并且系统中没有任何机制允许它改变这种支配关系。 
3.如果$x_i$等于全局最小值，则电梯$i$不晚于任何其他电梯到达每个楼层。 由于它在每一层都已经是最早的，所以它自动第一个到达顶层，不需要任何干预。 
4. 输出$0$如果电梯$i$具有最小开始时间，否则输出$-1$。 

### 为什么它有效

 不变的是，每层电梯的相对顺序仅取决于它们的启动时间，并且在所有楼层都是相同的。 由于所有电梯都以相同的速度运行，因此不会发生超车情况。 由于只有楼层的第一部电梯可以延迟，并且该身份是全局固定的，因此所有延迟都集中在同一部电梯上。 因此，任何按钮按下顺序都不能改变全局最早的电梯的身份，因此除了具有最小启动时间的电梯之外，没有其他电梯可以首先到达顶部。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    x = list(map(int, input().split()))

    mn = min(x)

    out = []
    for i in range(n):
        if x[i] == mn:
            out.append("0")
        else:
            out.append("-1")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案首先计算所有电梯的最短启动时间。 这是唯一重要的值，因为它决定了每个楼层第一个的独特电梯。 然后通过与该全局最小值的直接比较来确定每个查询输出。 

一个常见的错误是尝试模拟按钮效果或分布延迟的原因。 这些方法失败了，因为“先到”结构在楼层之间永远不会改变，从而使系统实际上是静态的。

 ## 边缘情况

 最重要的边缘情况是多台电梯共享最短启动时间。 在这种情况下，所有电梯在初始排序中同时都是最优的，并且由于关系是通过索引解决的，因此只有其中最小索引的电梯实际上是“无处不在的第一”。 然而，由于成功的条件仅仅是启动时间全局最小，因此具有该最小值的每个电梯都可以作为此公式中的答案目标。 

例如，如果输入是：```
3 10
5 1 1
```最小值为 1，由电梯 2 和电梯 3 共享。两者都输出 0，而电梯 1 输出 -1。 该算法直接处理此问题，因为它仅将相等性与最小值进行比较，从而正确捕获在最早启动行为中无法区分的所有电梯。
