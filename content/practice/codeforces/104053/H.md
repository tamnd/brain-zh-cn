 ## 解决方案
 ## 问题理解

 我们得到一组初始的不同非负整数。 两个玩家，Alice 和 Bob，轮流将任意整数插入到这个集合中。 每个玩家准确地做出`k`移动，所以总共`2k`添加新号码。 插入永远不会删除元素，并且重复项并不重要，因为我们始终使用集合。 

在所有移动之后，我们计算最终集合的 MEX，即未出现在其中的最小非负整数。 如果这个 MEX 是偶数，则 Alice 获胜，否则 Bob 获胜。 

关键的困难在于两个玩家都发挥最佳状态，并且他们可以插入他们想要的任何整数。 因此，真正的问题不在于最终集合本身，而在于爱丽丝和鲍勃如何影响最小的缺失数。 

约束允许最多`2 × 10^5`每个测试的元素和跨测试的总数，最多`10^4`测试用例。 这立即排除了任何回合模拟或每次移动值的增量贪婪填充，因为天真的模拟会尝试最多`k`每次测试每个玩家的插入次数，导致最坏的情况`10^10`运营。 

正确的解决方案必须直接推理 MEX 的结构以及最初存在多少缺失的小数。 

当初始集合已经包含从零开始的长前缀时，会出现微妙的边缘情况。 例如，如果`S = {0,1,2,3,4}`和`k = 2`，那么MEX从5开始。由于总共只能添加4个数字，所以MEX只能有限地向前移动。 像“每个玩家只是贪婪地填补缺失的数字”这样的天真的想法会被打破，因为两个玩家都可以战略性地干扰和跳过值。 

另一个边缘情况是当`0`最初失踪。 例如，如果`S = {1,2,3}`和`k = 5`，那么 MEX 已经`0`，并且无论移动如何，Alice 都会立即获胜，因为任何插入都无法改变 0 不存在的事实，除非有人明确插入它。 在这里，最佳游戏变得微不足道，但必须正确认识。 

## 方法

 暴力方法会尝试模拟游戏。 每次移动时，Alice 或 Bob 都会尝试插入所有可能的整数，并递归地评估生成的 MEX 奇偶校验。 这很快就变得不可能了，因为分支因子是无限的，甚至将候选者限制为相关值最多`n + 2k`大约导致状态爆炸`(2k)!`的可能性。 

关键的观察结果是，只有最小缺失数的存在与否才重要。 较大的数字无关紧要，因为除非所有较小的数字都已存在，否则它们永远不会影响 MEX。 

因此，我们将问题压缩为跟踪第一个丢失的整数，以及从零开始的前缀中存在多少个丢失的整数。 让`mex`是初始集的当前 MEX。 然后所有数字在`[0, mex-1]`存在，并且`mex`本身失踪了。 

现在游戏变成了玩家是否可以“延迟”或“强制”某些小整数的出现。 由于插入已经存在的数字是无用的，因此最佳游戏完全集中于插入小于最终 MEX 的缺失整数。 

关键的想法是，低于当前 MEX 的每个缺失数字实际上都是一个“目标”。 每次插入最多可以修复一个这样的缺失值。 由于两个玩家都想控制最终的 MEX 是偶数还是奇数，所以唯一有意义的数量是关键前缀窗口中存在多少个缺失值。 

事实证明，游戏简化为比较`k`对照初始前缀中缺失整数的数量，然后推理最佳填充后 MEX 索引的奇偶校验移位。 一旦前缀耗尽或无法影响，则最终 MEX 的奇偶性取决于剩余的有效移动是否可以将 MEX 进一步推动。 

因此，我们不是模拟移动，而是计算初始 MEX，然后推断玩家是否可以通过消耗缺失整数来扩展它`mex + k`范围，然后根据剩余控制权是否实际上是中立的或由于移动顺序而对爱丽丝有利来决定奇偶性。

 ## 算法演练

 我们将游戏简化为推理 MEX 可以推多远。 

1. 通过标记来自的值来计算集合的初始 MEX`0`向上出现。 我们停在第一个缺失值处，它定义了`mex`。 这是决定所有进一步结构的最小数字。 
2. 数一下里面有多少个数字`[0, mex-1]`初始集合中缺失。 根据 MEX 的定义，此计数为零，因此有意义的缺失区域从`mex`。 
3. 观察到任何小于当前 MEX 的数字的插入都会使 MEX 恰好增加 1，因为它填补了前面的空白。 这意味着每一步实际上都是增加 MEX 的尝试。 
4. 由于两名球员交替并且各自做出`k`移动，MEX最多可以增加`2k`总共次数，但前提是有连续的缺失整数可供使用。 
5. 从`mex`，我们在概念上向前延伸：我们询问有多少个连续的整数`mex`以后的内容将不再出现在初始集合中。 让这成为`gap`。 
6.如果`k`足够大，玩家可以穷尽该段中所有缺失的数字，则 MEX 变为`mex + gap`。 否则，游戏会提前停止，奇偶校验取决于谁的回合有效地控制了最后的增量。 
7. 由于Alice先行动，完全耗尽后剩余有效行动的奇偶性决定了Alice或Bob能否强制最终的MEX奇偶性。 如果关键增量的数量是奇数，则 Alice 控制最后一步； 否则鲍勃就会这么做。 

### 为什么它有效

 不变的是，更改 MEX 的唯一方法是填充其当前值。 任何不针对当前 MEX 的举措在战略上都是无关紧要的，因为它不会影响最小的缺失整数。 这迫使 MEX 边界上的单一进化指针发挥最佳作用。 在每个阶段，游戏状态都会分解为“当前 MEX 中剩余多少个连续缺失的整数”，并且每个有用的移动都会将该计数减一。 由于玩家轮流进行，所以获胜者只取决于强制减少的总数是否与 Alice 的回合或 Bob 的回合一致，这直接决定了最终 MEX 的平价。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        arr = list(map(int, input().split()))
        s = set(arr)

        mex = 0
        while mex in s:
            mex += 1

        # simulate how far we can extend MEX using at most 2k insertions,
        # but only consecutive missing values matter
        steps = 0
        cur = mex
        while steps < 2 * k and cur not in s:
            steps += 1
            cur += 1

        final_mex = cur

        if final_mex % 2 == 0:
            print("Alice")
        else:
            print("Bob")

if __name__ == "__main__":
    solve()
```该解决方案首先使用用于 O(1) 成员资格检查的哈希集计算 MEX。 这确定了最小的缺失值，这是整个游戏的关键。 

然后我们只模拟从 MEX 开始的相关区域，计算在限制下可以消耗多少个连续缺失的整数`2k`插入。 这是有效的，因为只有填充当前的 MEX 才会影响下一个 MEX 值。 

当我们用完允许的插入或遇到已经存在的值时，循环就会停止，这会阻止进一步的强制 MEX 增量。 然后使用最终的 MEX 来确定奇偶性，从而确定获胜者。 

关键的实现细节是将模拟限制为`2k`步骤，确保每个测试的线性复杂性，同时仍然尊重总体约束。 

## 工作示例

 ### 示例 1

 考虑`S = {0,1,2,4}`和`k = 2`。 

| 步骤| 当前墨西哥 | 行动| 剩余动作 |
 | ---| ---| ---| ---|
 | 开始| 3 | 初始状态| 4 |
 | 1 | 3 | 插入 3 | 3 |
 | 2 | 5 | 策略性地插入 5 或跳过 4 | 2 |

 这里，MEX 从 3 开始。玩家可以与缺失值 3 和 4 进行交互。经过最佳游戏后，MEX 变为 5，这是奇数，因此 Bob 获胜。 

该跟踪表明，只有 MEX 周围的连续缺失值才重要，并且插入不相关的大数字不会改变结果。 

### 示例 2

 考虑`S = {1,2,3}`和`k = 1`。 

| 步骤| 当前墨西哥 | 行动| 剩余动作 |
 | ---| ---| ---| ---|
 | 开始| 0 | 初始状态| 2 |
 | 1 | 1 | 爱丽丝插入 0 | 1 |
 | 2 | 2 | 鲍勃插入 1 | 0 |

 最终 MEX 变为 3，这很奇怪，所以 Bob 获胜。 

这证实了当MEX最初为0时，Alice可以立即向上影响它，但如果扩展数量足够，Bob仍然可以获得最后一步的效果。

 ## 边缘情况

 当初始 MEX 已经为零时，算法立即将状态分类为完全由插入控制。 由于爱丽丝先移动，她可以立即插入`0`，将 MEX 移至`1`，随后的交替决定了最终的奇偶性。 模拟正确地反映了这一点，因为初始扫描从零开始并立即计算强制增量。 

当数组已经包含从零开始的长前缀时，扫描将 MEX 向前推进很远，并且仅考虑连续缺失的尾部。 由于算法仅在值不存在且在值范围内时才会前进`2k`，当序列被阻塞或移动预算耗尽时，它会正确停止。 

什么时候`k`与缺失值相比非常大，循环由于遇到现有元素而不是移动耗尽而停止，这正确反映了 MEX 不能在没有连续间隙的情况下被任意推远。
