 ## 解决方案
 ## 问题理解

 我们得到了一系列应用于单堆石头的操作。 每次操作要么添加一颗石子，要么移除一颗石子。 关键的限制是，每当发生移除时，在该操作之前，堆中保证至少包含一颗石头，这意味着我们在实际过程中永远不会观察到无效的移除。 

然而，我们不知道石头的初始数量。 目标是选择尽可能小的起始值，以便可以执行整个序列，而无需尝试从空堆中删除，然后计算应用所有操作后的最终堆大小。 

困难在于起始值影响可行性。 如果我们起点太低，某些前缀的移除将变得不可能。 如果我们起点太高，最终值也会高于必要值。 我们需要避免无效状态的最小起始值，然后计算最终的结果值。 

约束条件$n \le 100$足够小，任何线性扫描或前缀模拟就足够了。 即使对可能的起始值进行二次暴力也是可以接受的，但没有必要。 

当序列以移除开始时，会出现微妙的边缘情况。 例如，输入`---`强制初始堆至少为 3，否则第一个操作已经失败。 另一种情况是混合序列，例如`-+--`，其中早期增量可能会也可能不会抵消后来的下降，具体取决于初始偏移量。 假设从零开始并且仅在本地“修复”无效状态的简单模拟可能会低估所需的初始值。 

## 方法

 蛮力策略会尝试所有可能的初始堆大小。 对于每个候选起始值$x$，我们模拟序列：我们加 1`+`并减去 1`-`，拒绝任何桩变为负值的模拟。 其中有效$x$，我们选择最小的并计算最终结果。 

这是可行的，因为状态空间很小，但本质上效率很低，因为我们可以模拟最多$n$每个候选人的操作$x$， 和$x$本身可以达到$n$。 这导致$O(n^2)$模拟，在这里仍然很好，但隐藏了真实的结构。 

关键的观察是，唯一重要的是如果我们从零开始，操作的前缀和会变得多低。 每个`-`减少余额，每个`+`增加它。 如果我们定义一个从零开始的运行余额，它所达到的最小值告诉我们必须将整个过程向上移动多少，这样它就不会变成负值。 

如果最小前缀和为$m$，那么我们至少需要从$-m$宝石以确保有效性。 在该移位之后，最终结果只是所有操作加上此偏移量的总和，但由于我们只需要最小的最终堆大小，因此它会折叠为直接计算。

 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 已接受但没有必要 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们诠释`+`作为+1和`-`作为 -1 并跟踪运行的前缀和，就好像初始堆为零一样。 

1. 初始化变量`balance = 0`，它代表相对于未知基线的当前宝石。 这模拟从零开始。 
2. 初始化`min_balance = 0`，它记录扫描过程中遇到的最小前缀值。 这捕获了序列尝试低于零的程度。 
3. 从左到右扫描字符串。 对于每个字符：

 如果是的话`+`, 增量`balance`1. 如果是`-`, 递减`balance`1.
 4.更新后`balance`， 更新`min_balance = min(min_balance, balance)`。 如果我们从零开始，这将跟踪该序列将导致的最严重的赤字。 
5. 完成所有操作后，所需的最少起始石为`-min_balance`。 这会改变整个轨迹，使最低点变为零。 
6. 最终堆大小只是调整后的期末余额，等于总和加上所需的偏移量。 由于从零开始的最终余额是已知的，我们直接将其计算为`balance - min_balance`。 

### 为什么它有效

 前缀和描述了如果我们从零开始，堆将如何演变。 任何负前缀值都对应于不可能的中间状态。 向初始堆添加恒定的偏移量会使整个前缀曲线向上移动，而不会改变状态之间的相对差异。 使所有前缀非负的最小偏移量恰好是最小前缀和的绝对值。 一旦移动，最终状态就被唯一确定，因此这种构造产生最小的有效起始配置，从而产生最小可能的最终桩尺寸。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()

balance = 0
min_balance = 0

for ch in s:
    if ch == '+':
        balance += 1
    else:
        balance -= 1
    if balance < min_balance:
        min_balance = balance

# minimal initial stones needed
start = -min_balance

# final stones after all operations
print(balance + start)
```该代码跟踪算法中描述的相同前缀过程。 这`balance`变量表示操作的净效果，而`min_balance`捕获最严重的赤字。 计算出的`start`是防止出现任何中间负堆大小的最小安全偏移量。 将其添加到最终平衡中即可得到可实现的最小最终堆。 

一个常见的实施陷阱是忘记最终答案取决于总余额和最小前缀。 仅使用总和在序列上失败，例如`--+`，其中中间状态比最终结果更重要。 

## 工作示例

 ### 示例 1：`---`| 步骤| 运营| 平衡| 最低余额 |
 | --- | --- | --- | --- |
 | 1 | - | -1 | -1 |
 | 2 | - | -2 | -2 |
 | 3 | - | -3 | -3 |

 这里最小前缀是-3，所以我们必须从 3 个石头开始。 最终从零开始的余额是-3，所以调整后的结果是-3 + 3 = 0。 

这显示了每个步骤都会强制一个新的最小值的情况，并且答案完全由前缀深度驱动。 

### 示例 2：`-+-+`| 步骤| 运营| 平衡| 最低余额 |
 | --- | --- | --- | --- |
 | 1 | - | -1 | -1 |
 | 2 | + | 0 | -1 |
 | 3 | - | -1 | -1 |
 | 4 | + | 0 | -1 |

 最小前缀是 -1，所以我们从 1 个石头开始。 最终余额为 0，所以答案为 1。 

这表明，即使净和为零，早期的下跌仍然决定了所需的初始偏移量。

 ## 边缘情况

 对于像这样的序列`---`，前缀模拟变为-1、-2、-3。 算法记录`min_balance = -3`，因此所需的起始值为 3。应用完整序列后，调整后的最终结果为零，这与所有初始石子都被完全消耗的直觉相匹配。 

对于像这样的序列`-+-+`，前缀在第一次操作时降至 -1，并且永远不会降低。 算法集`min_balance = -1`，因此起始值为 1。从零开始的最终余额为 0，因此输出为 1，正确反映了需要一个初始石头才能在第一次移除中幸存下来。 

对于像这样的序列`+-+-`，余额在 0 和 1 之间振荡，不会变为负值。 最小前缀保持为 0，因此不需要初始宝石。 最终结果也是0，这与添加和删除相互抵消且不存在可行性问题的情况一致。
