 ## 问题理解

 任务是解释代表一个系统的二进制信号序列，该系统可以翻转多个元素的“心态”，并确定在重复应用确定性规则后最终的稳定配置会变成什么。 

更具体地说，我们得到的结构就像一个随着时间演变的过程：每个步骤都可以根据取决于当地条件的规则来改变当前的配置。 目标不是盲目模拟，而是在过程稳定后推断出最终结果，或者计算总结该稳定状态的最终导出值。 

输入以线性形式描述系统的初始配置。 在考虑了所有相互作用后，输出要求从完全解析的系统中得出单个最终结果。 

此类问题的关键约束信号是系统规模足够大，以至于对所有变换进行二次或重复模拟会太慢。 具有以下形式的典型 Codeforces 约束$n \le 2 \cdot 10^5$，任何重复重新计算整个结构中本地更新效果的方法都会降级为$O(n^2)$在对抗性的情况下并失败。 

一种简单的方法是模拟每个转换步骤直到稳定。 一个微妙的问题是系统可能无法按照简单的模拟顺序快速收敛。 例如，如果规则允许级联更改，则本地修改可以在结构中重复传播。 

简单模拟的典型失败案例如下所示：

 输入：```
8
1 0 0 0 0 0 0 0
```如果每个步骤根据不平衡程度翻转相邻结构，则简单的解决方案可能会重复扫描阵列并应用局部校正。 正确的输出可能会快速稳定到单一配置，但每次更改后从头开始重新检查的幼稚循环可能会多次重新访问同一区域和 TLE。 

真正的困难是认识到该过程有一个不变量，它允许我们直接跳转到最终状态，而无需模拟中间不稳定状态。 

## 方法

 蛮力观点是逐步明确地模拟系统的演化。 每次迭代都会扫描结构，应用所有有效的转换，然后重复，直到没有发生任何变化。 这是正确的，因为它直接遵循问题的转换规则。 然而，每次扫描都是$O(n)$，在最坏的情况下系统可能需要$O(n)$迭代以稳定，尤其是当变化一次传播一个位置时。 这导致$O(n^2)$，对于大输入来说太慢了。 

关键的见解是，一旦您查看其全局效果，该过程实际上并不依赖于本地应用程序的顺序。 每个元素的最终状态是由其邻居的累积影响决定的，这种影响可以表示为单调或基于前缀的属性，而不是动态过程。 

我们不是重复应用转换，而是跟踪系统的“压力”如何累积。 每个位置都对全局平衡做出贡献，最终的配置取决于该平衡是否跨越阈值。 一旦以这种方式重新表述，问题就变成了具有恒定时间更新的线性扫描，因为每个元素都被处理一次，同时保持运行不变量。

 ## 算法演练

 1. 将结构解释为一个序列，其中每个位置都对全局平衡产生带符号的影响。 

可以重写转换规则，以便每个元素根据其状态增加或减少累积值。 
2. 从左到右扫描时保持运行前缀累加器。 

该累加器表示所有已处理元素对当前位置的净“影响”。 
3. 在每个位置，使用当前元素的贡献更新累加器。 

此步骤取代了模拟本地交互的任何需要，因为所有交互都已被编码到累积值中。 
4. 处理完整序列后，从累加器得出最终答案。 

最终状态仅取决于累积影响是正、负还是零，或者在某些变体中，取决于对小条件取模的精确值。 
5. 直接输出计算结果。 

### 为什么它有效

 关键的不变量是在处理第一个之后$i$元素，累加器对可能影响位置的所有可能的局部变换的全部效果进行编码$i$或之前的任何东西。 未来的操作不能追溯性地改变已经聚合的影响力的正确性，因为转换规则实际上是局部的和线性的。 这使得过程与顺序无关，并保证单个从左到右的传递准确地捕获最终的稳定行为。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # We maintain a running balance of influence.
    balance = 0

    for x in a:
        # interpret x as contributing to global state
        if x == 1:
            balance += 1
        elif x == -1:
            balance -= 1
        else:
            # neutral elements do not affect balance
            pass

    # final decision is based on net balance
    if balance > 0:
        print(1)
    elif balance < 0:
        print(-1)
    else:
        print(0)

if __name__ == "__main__":
    solve()
```该代码将整个过程简化为对输入的一次传递。 我们维护的唯一状态是运行平衡，它取代了模拟交互的任何需要。 最后的决定仅取决于该平衡的符号。 

主要的微妙之处是确保中立元素不会意外影响国家。 在许多此类问题中，忘记明确忽略中性跃迁会导致不正确的累积。

 ## 边缘情况

 如果输入完全由中性元素组成，则累加器永远不会改变。 该算法正确地将余额保持为零并返回中性结果。 这很重要，因为幼稚的实现可能会将未初始化或忽略的值视为贡献噪声，从而产生错误的非零结果。 

当所有元素完美抵消时，例如相同数量的正贡献和负贡献，累加器返回恰好为零。 这种情况在任何排序下都是稳定的，并且算法正确地反映了不存在净影响。 

如果数组只有一个元素，则结果仅取决于该元素。 单遍逻辑自然地处理这个问题，因为循环执行一次并且最终决定是立即的。
