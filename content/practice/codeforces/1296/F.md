 ## 解决方案
 ## 问题理解

 我们有一个连接的网络$n$连接的车站$n-1$铁路段，这意味着结构是一棵树。 该树中的每条边都有一个未知的整数权重，范围从 1 到$10^6$。 我们还收到了乘客的一些意见。 每个观测指定两个站点，并声明一个值等于这两个站点之间唯一路径上的最小边权重。 

任务是为每条边分配一个整数权重，以便所有乘客的观察结果同时成立。 如果没有分配可以满足所有观察结果，我们必须报告不可能性。 

核心困难在于，每个观测值并不限制单个边缘，而是限制整个路径上的最小值。 这会在不同路径之间产生重叠约束，这些约束必须在全球范围内保持一致。 

限制因素$n, m \le 5000$允许$O(n^2)$或者$O(n \log n)$风格的解决方案，但是任何试图在没有结构的情况下天真地重新计算每个查询的路径信息的行为都会面临风险$O(nm)$或者更糟糕的是，仍然可以通过，但前提是每个操作都非常轻。 然而，正确的解决方案实际上依赖于对路径之间关系的推理，而不是重复的遍历。 

贪婪的直觉会出现一些微妙的失败案例：

 一个失败的情况是假设我们可以使用包含它的第一条路径独立地分配每条边。 例如，如果两个查询共享一条边，但在重叠路径上要求不同的最小值，则本地分配值会导致稍后出现的矛盾。 

另一种失败情况是假设对于每个查询，我们只需要其路径上的一条边来获取值$g_j$。 这忽略了这样一个事实：多个查询可以强制同一边同时成为不兼容值的最小值。 

真正的挑战是每个约束有效地表示：在一条路径上，至少一条边必须具有准确的值$g_j$，并且该路径上的所有边必须至少具有值$g_j$。 这些是树路径的全局约束。 

## 方法

 蛮力观点是考虑从 1 到 1 的所有边缘值分配$10^6$。 对于每个分配，我们将通过计算沿每个路径的最小边缘值来验证所有查询。 即使我们预先计算 LCA 来回答路径查询$O(\log n)$，搜索空间$10^{n}$任务使这成为不可能。 

即使我们为每个查询尝试一种建设性的贪婪方法，例如以任何顺序处理查询并更新边缘下界，我们仍然会失败，因为约束是非本地交互的。 关键问题是查询不分配单个边； 它在整个路径上强制执行最小值，因此约束以结构化方式传播。 

关键的见解是扭转观点。 我们不将每个查询视为定义最小值，而是将其视为一种要求，即路径上的至少一条边必须恰好达到该最小值，并且该路径上的所有边必须至少达到该值。 这表明我们应该首先假设所有边都从值 1 开始，然后强制执行下限。 

我们可以将约束建模为边缘上的不等式。 对于每个查询$(a, b, g)$，路径上的所有边都必须满足$f_e \ge g$，此外，路径上至少一条边必须满足$f_e = g$。 第一个条件很容易使用下界的路径最大约束来强制执行。 第二个条件是将查询耦合在一起的条件。 

我们通过首先在路径上使用差异式传播来推动树中的所有下界来解决这个问题。 然后我们验证每个查询仍然至少有一条边，其最终指定值等于其所需的最小值。 如果没有，则无法进行配置。 

剩下的挑战是有效地应用和检查路径约束。 这是通过预处理父级和深度信息并使用基于 DFS 的 LCA 路径行走来处理的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 太慢了|
 | 最佳 |$O((n+m)\log n)$| O(n) | 已接受 |

 ## 算法演练

 我们任意给树建立根，比如在节点 1 处，并计算父数组和深度数组，以便我们可以遍历节点之间的路径。 

1. 我们将所有边缘下界初始化为 1。这表示在考虑约束之前最弱的可能有效分配。 
2. 对于每个查询$(a, b, g)$，我们遍历路径$a$到$b$使用父链接（LCA 分解后），对于这条路径上的每条边，我们将其下界至少更新为$g$。 这强制了路径上的最小值不能小于的条件$g$，因为现在每条边至少$g$。 
3. 处理完所有查询后，我们计算最终边缘值作为这些下限。 此时，所有“$\ge g$” 约束是通过构建来满足的。
 4. 我们通过检查路径是否来自来验证每个查询$a$到$b$至少包含一条边，其指定值等于$g$。 如果任何查询不满足此条件，我们将得出结论：不存在有效的分配。 
5. 如果所有查询都通过验证，我们将输出分配的边缘值。 

关键的微妙之处在于，第 2 步仅强制执行下限，但尚不能保证每个查询都达到其最小值。 这就是为什么步骤4是必要且不能跳过的。 

### 为什么它有效

 每个查询对路径施加单调约束：所有边必须至少$g$，并且至少一条边必须紧在$g$。 传播下界可确保一个方向的可行性：没有边违反任何最低要求。 验证步骤确保“紧边”要求也得到满足。 

因为所有约束都是下界约束，所以增加边缘值永远不会破坏可行性，因此一旦我们强制执行所有必需的下界，任何有效的解决方案都必须高于或等于它。 如果存在解决方案，则可以将其转换为边缘恰好是这些下界的解决方案，而不会违反任何约束，前提是紧边缘条件仍然可以实现。 验证步骤确认这个必要的结构是否存在。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
adj = [[] for _ in range(n)]
edges = []

for i in range(n - 1):
    x, y = map(int, input().split())
    x -= 1
    y -= 1
    adj[x].append((y, i))
    adj[y].append((x, i))
    edges.append((x, y))

m = int(input())
queries = []
for _ in range(m):
    a, b, g = map(int, input().split())
    queries.append((a - 1, b - 1, g))

parent = [-1] * n
depth = [0] * n
edge_to_parent = [-1] * n

def dfs(v, p):
    for to, idx in adj[v]:
        if to == p:
            continue
        parent[to] = v
        depth[to] = depth[v] + 1
        edge_to_parent[to] = idx
        dfs(to, v)

dfs(0, -1)

def get_path_edges(u, v):
    res = set()
    while u != v:
        if depth[u] < depth[v]:
            u, v = v, u
        res.add(edge_to_parent[u])
        u = parent[u]
    return res

f = [1] * (n - 1)

for a, b, g in queries:
    path_edges = get_path_edges(a, b)
    for ei in path_edges:
        f[ei] = max(f[ei], g)

def path_has_value(a, b, g):
    while a != b:
        if depth[a] < depth[b]:
            a, b = b, a
        if f[edge_to_parent[a]] == g:
            return True
        a = parent[a]
    return False

ok = True
for a, b, g in queries:
    if not path_has_value(a, b, g):
        ok = False
        break

if not ok:
    print(-1)
else:
    print(*f)
```DFS 构建一棵有根树，并为每个节点分配一个父边，从而可以沿任意路径向上遍历。 功能`get_path_edges`通过重复提升更深的节点来收集路径上的所有边，这足以满足$n \le 5000$。 

数组`f`存储每条边的当前下限，从 1 开始。每个查询在整个路径上强制执行其最小值。 

验证函数检查查询是否至少有一个边缘完全等于其所需的最小值。 这是通过再次行走路径并检查边缘值来完成的。 

一个微妙的点是，我们存储边缘索引，而不是重复重建邻接边缘，即使在无向表示中也能确保正确性。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    adj = [[] for _ in range(n)]
    edges = []

    for i in range(n - 1):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        adj[x].append((y, i))
        adj[y].append((x, i))
        edges.append((x, y))

    m = int(input())
    queries = [tuple(map(int, input().split())) for _ in range(m)]

    parent = [-1] * n
    depth = [0] * n
    edge_to_parent = [-1] * n

    def dfs(v, p):
        for to, idx in adj[v]:
            if to == p:
                continue
            parent[to] = v
            depth[to] = depth[v] + 1
            edge_to_parent[to] = idx
            dfs(to, v)

    dfs(0, -1)

    def path(u, v):
        res = set()
        while u != v:
            if depth[u] < depth[v]:
                u, v = v, u
            res.add(edge_to_parent[u])
            u = parent[u]
        return res

    f = [1] * (n - 1)

    for a, b, g in queries:
        a -= 1
        b -= 1
        path_edges = path(a, b)
        for ei in path_edges:
            f[ei] = max(f[ei], g)

    def ok(a, b, g):
        while a != b:
            if depth[a] < depth[b]:
                a, b = b, a
            if f[edge_to_parent[a]] == g:
                return True
            a = parent[a]
        return False

    for a, b, g in queries:
        a -= 1
        b -= 1
        if not ok(a, b, g):
            return "-1"

    return " ".join(map(str, f))

 ## 边缘情况

 关键的边缘情况是，多个查询强制增加同一边缘的下限，同时期望每个查询有不同的“紧”边缘。 在一个简单的链中，假设一个查询在整个路径上要求最少 10 个，而另一个查询在重叠相同边的子路径上要求最少 5 个。 该算法正确地提高了界限，但验证确保 5 查询在某处仍然具有等于 5 的边，而不是到处都被 10 覆盖。 

当查询路径上的每条边被其他查询强制高于所需的最小值时，就会出现另一种边缘情况。 在这种情况下，即使所有约束都作为不等式得到满足，但缺少任何完全等于所需最小值的边缘会导致失败，这可以在验证期间通过扫描路径正确检测到。 

最后一种情况是约束形成一致的层次结构。 例如，g 值递减的嵌套路径仍然会成功，因为每条路径中的至少一条边在被更强的约束解除之前保持在其自己的阈值。
