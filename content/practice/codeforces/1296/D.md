 ## 解决方案
 ## 问题理解

 我们得到了一系列按固定顺序排列的怪物。 每个怪物都有一定的生命值，必须从左到右依次击败它们。 与怪物的战斗是回合制的：首先你攻击，然后对手攻击，如此重复，直到怪物的生命值降至零或以下。 

你的攻击总是会造成固定数量的伤害，每当你的攻击杀死一个怪物时，你就会为该怪物赢得一分。 对手也在自己的回合中造成固定伤害，但他们从不贡献得分。 不同的是，你可以在所有战斗中取消对手的回合，次数有限，并且每次取消都会跳过一次对手的攻击。 

目标是最大化你个人消灭的怪物数量，这相当于最大化你的攻击将怪物生命值降至零或更低的次数。 

限制很大：最多20万个生命值达到10^9的怪物，而且跳过的次数也很大。 这立即排除了逐次模拟每次攻击的可能性。 如果简单地实现的话，即使是模拟完整战斗的每个怪物循环也可能太慢，因为单个怪物可能需要最多 10^9 / 回合。 

关键的困难在于，跳过对手的攻击是一种全局资源。 对一个怪物使用跳跃会改变其他怪物所需的命中次数，因此我们必须决定如何在怪物之间分配跳跃。 

当假设我们总是想对最大的怪物使用跳跃时，就会出现一个天真的错误。 例如，即使跳跃多次，生命值非常高的怪物仍然可能无法“转化为点”，而较小的怪物可能只需要跳跃几次即可确保我们获得最后一击。 跳跃的好处取决于当前的交替模式，而不仅仅是原始健康状况。 

当贪婪策略一旦可用就使用跳过时，就会出现另一个微妙的失败情况。 这可能会浪费早期怪物的跳过次数，因为它们不需要获得分数，而为后来的怪物留下了足够的跳过次数，而在后期怪物中，进行小的调整就会产生增益。 

## 方法

 如果我们直接模拟每个怪物，我们可以计算出直到怪物死亡为止需要多少个“你然后对手”的完整循环。 对于给定的怪物，如果没有任何跳过，所需的攻击次数是固定的，但对手可能会插入额外的伤害回合，从而增加所需的循环次数。 可以尝试一步步模拟战斗，每当对手行动时消耗 k 个跳跃。 

这种暴力的想法是正确的，因为它准确地反映了规则。 然而，它可能会严重退化：一个健康状况良好的怪物可能需要数百万次交替回合，并且对于所有怪物来说，这都远远超出了可接受的限度。 

关键的观察是，每个怪物都可以被分配一个“成本”，即必须移除多少对手回合，这样你仍然可以在对手有效地延迟你最终击中之前杀死你。 我们不是模拟回合，而是计算每个怪物必须取消多少次对手击中才能保证怪物在你的回合死亡。 那么问题就变成了选择最大数量的怪物，其费用可以使用最多 k 次跳过来支付。

对于固定怪物，请考虑发生多少个完整循环（您攻击，对手攻击）直到其生命值降至零。 如果我们用 t 表示杀死它所需的攻击次数，那么在正常过程中，对手在你最后一击之前会采取行动 t−1 次。 如果我们希望你进行最后一击，我们需要确保对手不会干扰关键周期，从而将杀戮推向超出你回合对齐的范围。 这转化为所需跳过的对手回合数，具体取决于对手在你的终结攻击之前采取的行动次数。 

因此，每个怪物都会贡献一个成本值，而每次成功击杀都会贡献一个单位的奖励。 我们希望在总预算 k 下最大化我们可以承受的成本。 按升序对这些成本进行排序并尽可能多地选择最便宜的成本是最佳的，因为每个怪物都会提供相同的奖励，因此我们总是首先选择更便宜的转换。

 ## 算法演练

 我们为每个怪物计算对手跳过的最少次数，以确保我们得到它的分数。 

1. 对于每个怪物，计算您需要多少次命中：`t = ceil(h / a)`。 这是在不间断的情况下杀死它所需的攻击次数。 
2. 确定在你的最后一击之前通常会发生多少次对手回合。 在标准交替模式中，对手得到`t - 1`在怪物死亡之前进行攻击。 
3. 将其转化为成本：必须消除多少对手攻击，以便战斗不会“超出”您的最终命中对齐。 得出的成本是`cost = max(0, t - 1)`。 

这反映出每个对手的回合都会有效地延迟相对于你的攻击顺序的杀戮，而消除他们会加速你完成最后一击的进度。 
4. 将所有成本收集到一个数组中。 
5. 按升序对数组进行排序。 
6. 遍历排序后的成本，将它们累积到运行预算中。 每次添加成本不超过 k 时，取出该怪物并从 k 中减去其成本，将答案增加 1。 
7. 当无法支付下一次费用时停止。 

### 为什么它有效

 如果选择，每个怪物只会产生一分，并且需要跳过对手回合的固定独立成本。 该过程简化为在所有值都相等的单个背包约束下选择尽可能多的物品。 在这种情况下，按成本递增顺序选择项目是最佳的，因为用较便宜的未选择项目替换已选择的昂贵项目只能提高可行性，而不会减少数量。 这种交换论证保证了任何最优解都可以无损失地转化为贪婪解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b, k = map(int, input().split())
    h = list(map(int, input().split()))
    
    costs = []
    
    for hp in h:
        t = (hp + a - 1) // a
        cost = t - 1
        costs.append(cost)
    
    costs.sort()
    
    ans = 0
    for c in costs:
        if c <= k:
            k -= c
            ans += 1
        else:
            break
    
    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先将每个怪物减少为单个标量成本，表示必须消除多少对手中断。 上限除法计算所需的命中次数。 减一表示在你的最终攻击位置之前发生了多少次对手回合。 

排序确保我们总是首先将跳跃花费在最便宜的怪物上。 然后，贪婪循环执行简单的预算消耗过程。 

一个微妙的实现点是整数除法：使用`(hp + a - 1) // a`避免浮点错误并正确计算上限。 另一个细节是我们从不显式模拟转弯； 所有动态都被压缩到成本公式中。

 ## 边缘情况

 最小的单怪物案例表明，即使选择之间没有竞争，该公式也能正确减少。 只要有一只怪物和足够的力量，成本就变成零，并且总是被拿走。 

零跳跃场景证实该算法永远不会错误地假设自由转换； 只计算零成本的怪物。 

健康值非常大的情况强调成本可能很大，但排序和贪婪选择仍然可以安全地处理它们，而不会出现溢出或性能问题。
