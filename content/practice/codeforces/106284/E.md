 ## 解决方案
 ## 问题理解

 游戏包含一系列胡萝卜怪物。 克罗什只能直接攻击第一个还活着的怪物。 要到达后面的怪物，它之前的所有怪物都必须已经被击败。 

瞄准当前怪物的射击会对连续的格子造成越来越大的伤害。 被瞄准的怪物受到 1 点伤害，下一个受到 2 点伤害，下一个受到 3 点伤害，依此类推，直到`k`怪物。 拥有健康的怪物`h`受到伤害的`d`将其健康状况更改为`|h - d|`。 一旦怪物的生命值为零，它就会永远被击败。 

任务是找到击败每个怪物所需的最少射击次数。 

限制是问题的关键部分。 最多可以有`2 * 10^5`怪物，同时`k`至多是`200`。 执行与射击次数成正比的工作的模拟是不可能的，因为生命值可能很大。 即使是重复施加伤害直到怪物死亡的方法也可能需要数十亿次操作。 

的小值`k`告诉我们结构在哪里。 怪物只能受到前一个怪物的影响`k - 1`怪物，因为一次射击最多到达`k`职位。 我们需要避免迭代游戏的每一秒，而是一次处理大量相同操作的效果。 

一些边缘情况很容易被忽略。 

如果怪物已经被先前怪物的伤害杀死，则不得再次攻击它。 例如：```
1 2
5 1
```第一个怪物在 5 次射击后死亡。 在这些射击中，第二只怪物受到伤害 2 五次：`1 -> 1 -> 1 -> 1 -> 1`实际上，因为生命值更新是绝对差异，所以状态仍然是1。答案是总共6次射击，而不是第一个怪物之后的5+1次重复直接攻击。 只计算直接攻击而忽略侧面伤害的解决方案会犯这个错误。 

怪物在到达前方之前可能会变为零。 例如：```
2 1
1 2
```第一个怪物需要一击。 该射击对第二个怪物造成 2 点伤害，将其从 2 变为 0。答案是 1。始终分别与每个怪物战斗的幼稚的从左到右模拟将输出 2。 

必须以数学方式处理大量攻击。 例如，如果未来的怪物受到伤害`3`一百万次，模拟一百万次更新是不必要的。 重复的绝对差运算周期短，这是该解决方案使用的主要观察结果。 

## 方法

 蛮力的想法是反复射击当前的怪物直到它死亡。 如果怪物当前有生命值`h`，这正好需要`h`射击，因为它每次都会受到 1 点伤害。 每次射击后我们都会更新下一次的所有怪物`k - 1`职位。 

这种方法是正确的，因为它完全遵循游戏，但当健康值很大时就会失败。 具有生命值的单个怪物`10^18`已经需要不可能的迭代次数。 

使问题得以解决的观察结果是，未来的怪物在一场战斗中受到的伤害始终是相同的值。 如果怪物`i`正在受到攻击，怪物`i + j`收到`j + 1`每一次射击都会造成伤害。 我们只需要应用这个函数`x -> |x - d|`对于一个固定的小数多次`d`。 

这个函数有一个简单的模式。 写`x = q * d + r`， 在哪里`0 <= r < d`。 后`q`应用程序，该值变为`r`。 如果`r = 0`，怪物死了。 否则它会交替出现`r`和`d - r`。 这让我们可以在恒定的时间内跳过任意数量的重复更新。 

整个算法处理每个怪物一次并仅更新下一个`k - 1`怪物。 自从`k`很小，总工作量是有界的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(总镜头 * k) | O(n) | 太慢了|
 | 最佳| O(nk) | O(nk) | O(n) | 已接受 |

 ## 算法演练

 1.存储每个怪物当前的生命值。 我们从左到右处理怪物，因为游戏顺序是由只有第一个活着的怪物才能被攻击的规则所强制的。 
2.对于当前怪物，如果其生命值已经为零，则跳过它。 先前的攻击已经将其击败。 
3. 否则，设其当前健康状况为`h`。 怪物确实需要`h`射击，因为每次直接攻击都会造成伤害 1. 添加`h`到答案并将怪物标记为已击败。 
4. 在这些期间`h`截图，更新下一个`k - 1`怪物。 远处的怪物`j`受到伤害`j + 1`在每次射击时，因此对固定的伤害值应用重复的绝对差运算。 
5. 申请`x -> |x - d|`确切地`t`次，分`x`经过`d`。 如果`t`小于商，答案是`x - t*d`。 否则，剩余部分为零或二值循环。 

为什么它有效：

 第一个活着的怪物总是只受到 1 点伤害，所以它的生命周期就是它当前的生命值。 其他所有怪物仅受之前怪物的影响，并且这些效果可以被压缩，因为每次战斗都会重复应用一个固定的变换。 该算法维护每个尚未处理的怪物的准确健康状况，因此当怪物到达前面时，存储的值正是真实游戏会产生的状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def apply_damage(x, d, t):
    if x == 0:
        return 0

    q, r = divmod(x, d)

    if t < q:
        return x - t * d

    if r == 0:
        return 0

    if (t - q) % 2 == 0:
        return r
    return d - r

def solve():
    n, k = map(int, input().split())
    h = list(map(int, input().split()))

    ans = 0

    for i in range(n):
        if h[i] == 0:
            continue

        shots = h[i]
        ans += shots
        h[i] = 0

        for j in range(1, k):
            if i + j >= n:
                break
            if h[i + j] != 0:
                h[i + j] = apply_damage(h[i + j], j + 1, shots)

    print(ans)

if __name__ == "__main__":
    solve()
```功能`apply_damage`是数学捷径。 商`q`代表有多少个完整的大小块`d`可以在到达剩余部分之前将其移除。 如果申请数量没有达到该点，该值就会减少`d`每次。 

达到余数后，就只有两种可能的状态。 余数为零意味着怪物已经死了。 非零余数在之间交替`r`和`d - r`，因此只有剩余操作次数的奇偶性很重要。 

主循环遵循游戏的强制顺序。 当前怪物将其生命值贡献给答案，变为零，然后仅影响下一个怪物`k - 1`职位。 每次更新之前检查零健康状况可防止已击败的怪物再次发生变化。 

Python 整数不会溢出，这是必要的，因为答案可能会超过 32 位限制。

 ## 边缘情况

 对于已经被先前的攻击杀死的怪物，算法会在处理之前检查其是否为零。 在输入中```
2 1
1 2
```第一个怪物需要一击。 第二只怪兽受到 2 伤害并变为零。 现在存储的生命值是`[0, 0]`，所以答案是`1`。 

对于大量的重复变换，该算法从不为每个镜头执行一次更新。 考虑一个健康的怪物`1000000000`受到伤害`2`为了`500000000`镜头。 该变换通过除法进行压缩：`1000000000 = 500000000 * 2 + 0`因此，在这些操作之后，怪物立即归零。 该函数在常数时间内返回零。 

为了`k = 1`，每次射击只影响当前怪物。 内部更新循环运行零次，每个怪物只需贡献其初始生命值。 这与游戏相符，因为没有溅射伤害。 

对于生命值小于传入伤害的怪物，直接处理绝对差行为。 如果怪物有生命值`3`并受到伤害`5`，就变成`2`，不为零。 循环公式保留了这种行为，因为它基于精确的变换而不是普通的减法。
