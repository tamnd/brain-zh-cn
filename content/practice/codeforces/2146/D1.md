 ## 解决方案
 ## 问题理解

 我们有两个整数，`l`和`r`， 在哪里`l`在这个简单版本中始终为零，并且`r`少于200,000。 由此，我们定义一个数组`b`包含来自的每个整数`l`到`r`，包含在内。 我们可以排列这个数组的副本，我们称之为`a`。 任务是重新排序`a`使得相应元素按位或的和`a`和`b`最大化，然后报告最大总和以及一个有效的排序`a`。 

自从`l=0`， 大批`b`简直就是`[0, 1, 2, ..., r]`。 数组的长度，`n`， 是`r - l + 1`，这只是`r + 1`。 约束条件允许`n`所有测试用例的数量大约为 200,000 个。 这排除了暴力排列，因为`n!`是一个天文数字，如果对所有测试用例求和，即使 O(n²) 成对比较也会太慢。 我们需要一个 O(n log n) 或 O(n) 的解决方案。 

棘手的部分是理解如何最大化按位或的总和。 像将每个配对这样粗心的方法`b[i]`与自身或简单地反转数组并不总是产生最大和。 例如，如果`b = [0,1,2,3]`，按降序配对`[3,2,1,0]`给出总和`3+3+3+3 = 12`，这确实是最大值。 洞察力是高位`b[i]`需要与中的数字匹配`a`设置互补位以最大化 OR。 

## 方法

 一个天真的方法是尝试每一个排列`a`，计算每个 OR 的总和，并选择最大值。 这在原则上是正确的，但完全不可行，因为排列的数量呈阶乘增长。 甚至生成所有对`(a[i], b[i])`以暴力方式是 O(n²)，这超出了我们的时间限制`n`最多200,000。 

关键的观察结果是按位或运算对于设置位来说是单调的。 这意味着具有较高位设置的较大数字在“或”和中支配较小数字。 我们想要每一个`b[i]`与一个配对`a[j]`确保 OR 中包含尽可能多的高位。 这自然会导致贪婪的方法：匹配数字，以便高位与当前有零的位置对齐`b[i]`。 实际上，实现此目的的一个简单方法是反转数组，将最大的数字放在最小的位置上。 自从`l=0`和`b`正在增加，正在逆转`a`足以最大化每个测试用例中的总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 贪心逆 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例的数量，`t`。 
2. 对于每个测试用例，请阅读`r`（自从`l=0`）。 
3. 构建`b`作为`[0, 1, 2, ..., r]`。 
4. 构建`a`作为`[0, 1, 2, ..., r]`最初，然后将其反转为`[r, r-1, ..., 0]`。 
5. 计算总和`a[i] | b[i]`为所有人`i`从 0 到`r`。 
6.输出和以及反转后的数组`a`。 

为何有效：倒车`a`保证最大的数字与最小的数字对齐`b`。 这确保了 OR 运算在每个位置添加尽可能多的高位。 自从`b`严格递增并且`l=0`，没有其他排列可以产生更高的总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    l, r = map(int, input().split())
    n = r - l + 1
    a = list(range(l, r + 1))[::-1]  # reversed array
    total = sum(a[i] | i for i in range(n))
    print(total)
    print(' '.join(map(str, a)))
```代码首先读取测试用例的数量。 对于每个测试用例，它构建`a`作为相反的序列`l`到`r`。 OR 和是通过迭代索引并对每个索引进行或运算来计算的`a[i]`和`b[i]`（这只是`i`自从`l=0`）。 反转数组是必要的； 如果我们忘记反转，我们只需将数字与它们本身相加，这会产生一个严格较小的总和。
