 ## 解决方案
 ## 问题理解

 我们有一个数组，它从左到右一次增长一个元素。 添加每个新元素后，我们查看恰好在这个新位置结束的所有子数组。 在这些子数组中，我们想要最大化特定分数的子数组。 

子数组的分数是以稍微间接的方式定义的。 首先计算子数组的 MEX，这意味着子数组中缺少的最小非负整数。 然后计算子数组中有多少元素严格大于该 MEX。 该计数就是子数组的权重。 

所以在每个位置`i`，我们要问：在所有细分市场中`[l, i]`，超过该段 MEX 的最大可能元素数是多少。 

困难来自循环依赖：MEX 取决于包含哪些值，但权重取决于 MEX。 更改左端点会以耦合方式更改两者。 一种简单的方法是重新计算 MEX 并计算每个`(l, i)`对，这对于`n`最多`3e5`。 

一个关键的约束含义是，尝试所有子数组的任何解决方案对于每个测试用例都是二次的，因此立即不可行。 即使每个左指针动态维护 MEX 也会导致每次更新至少产生对数开销，总体而言仍然太慢。 

当数组包含较大间隙或重复值时，会出现微妙的边缘情况。 例如，如果所有值都等于 0，则任何子数组的 MEX 为`1`，因此权重始终为零。 天真的直觉可能表明扩大或缩小间隔可以增加重量，但在这种情况下它永远不会改善，并且不正确的贪婪扩展策略很容易过度计算。 

当 MEX 在包含缺失的少量数字后大幅跳跃时，会发生另一个棘手的情况，导致许多元素停止对权重做出贡献。 例如，添加一个`1`进入仅包含零的段将 MEX 从`1`到`2`，突然使所有`2+`相关元素。 这种非单调行为是导致暴力推理失败的原因。 

## 方法

 直接暴力法修复端点`i`并尝试每一个起点`l`，计算 MEX 并计算大于它的元素。 从头开始计算 MEX 需要`O(n)`在最坏的情况下或`O(log n)`具有频率结构，计数与段长度呈线性关系。 这给出了总体`O(n^3)`或者充其量`O(n^2 log n)`解决方案，这对于`3e5`。 

结构见解是，MEX 仅由以下值的存在决定：`0`向上。 如果子数组包含所有数字`0..k-1`，那么它的 MEX 至少是`k`。 因此，我们可以考虑在保持小值的一定覆盖范围的同时可以将子数组扩展多远，而不是考虑任意子数组。 

对于固定的右端点`i`，考虑选择左端点`l`。 当我们移动时`l`向右，我们从子数组中删除元素。 这只能增加 MEX 或保持不变，因为删除元素不能在已经缺失的元素中引入缺失值。 然而，增加 MEX 会降低定义“大于 MEX”的阈值，而缩小子数组会减少可用候选。 我们要利用这两种效应之间的平衡。 

关键思想是重新构建问题：我们维护一个动态窗口，在其中控制丢失的小值数量，而不是显式跟踪每个段的 MEX。 对于墨西哥候选人`k`，子数组必须包含所有值`0..k-1`。 在所有以以下结尾的子数组中`i`，最好的后缀是仍然满足此约束的最长后缀，因为包含更多元素只会增加大于的元素数量`k`或在不破坏可行性的情况下做出同等贡献。 

这导致了单调结构：`k`增加，所需的窗口变得更难以维持，因此最佳段以可预测的方式移动。 因此，我们可以间接维护每个可能的 MEX 阈值的频率和滑动左指针。 

更有效的视角是针对每个可能的 MEX 值修复正确的端点并进行计算`k`，其 MEX 恰好为的段所贡献的最佳可能权重`k`。 各值`k`受到每个数字至少出现一次的限制`< k`在该段中，可以通过上次看到的位置进行跟踪。 使元素数量最大化的段大于`k`是在最早违反这些约束之后开始的后缀。 

通过维护，对于每个`k`，所需值缺失的最早位置，我们可以得出有效的左边界。 然后我们计算大于的元素`k`在值空间上使用前缀计数或 Fenwick 树。 由于值的边界为`n`，我们可以增量地维护频率前缀和。 

最后，而不是迭代所有`k`，我们观察到只有实际出现在有效性边界附近的值才重要，并且随着我们的移动，更新可以增量处理`i`。 这将过程简化为大致`O(n log n)`并仔细记账。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 从左到右处理数组，维护当前前缀中值的频率计数。 这使我们能够回答有关以任何结尾的后缀的 MEX 相关查询`i`无需从头开始重新计算。 
2. 对于每个位置`i`，保持最小值`mex`使得某些数字在`[0, mex)`当前窗口中缺少结束于`i`。 这可以增量更新，因为添加新元素仅影响一个频率桶。 
3. 跟踪每个值出现足够频繁以包含在有效 MEX 候选段中的最早位置。 这定义了给定 MEX 的可行性。 
4.对于当前`i`，通过将左边界尽可能向左扩展来计算候选段，同时保留所有值`< k`展示。 这给出了每个 MEX 候选者的最大窗口。 
5. 对于每个候选窗口，计算有多少个元素大于`k`。 由于值是有界的，因此需要维护一个前缀频率结构，以便可以通过以下方式获得该计数`O(1)`或者`O(log n)`。 
6.职位的答案`i`是所有有效 MEX 候选者的最大值。 

### 为什么它有效

 任何以以下结尾的有效子数组`i`有一个明确定义的 MEX`k`，并且必须包含所有值`0..k-1`。 在所有此类子数组中，扩展左边界直到这些所需值之一消失之前只能增加或维持大于的元素数量`k`，因为删除低于或等于的元素`k`永远不会增加上面元素的数量`k`。 因此，对于每个可能的 MEX，最佳子阵列是由可行性约束唯一确定的，并在所有子阵列之间进行比较`k`产生全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        freq = [0] * (n + 2)
        present = 0
        mex = 0

        res = [0] * n
        # right endpoint fixed at i
        l = 0

        for i in range(n):
            x = a[i]
            if x <= n + 1:
                freq[x] += 1

            while freq[mex] > 0:
                mex += 1

            # compute best weight for this i
            # try shrinking left while maintaining structure implicitly
            # maintain a copy window counts
            cnt = [0] * (n + 2)
            cur_mex = 0
            best = 0

            for j in range(i, -1, -1):
                v = a[j]
                cnt[v] += 1
                while cnt[cur_mex] > 0:
                    cur_mex += 1

                # weight = number of elements > cur_mex in [j..i]
                # compute by scanning freq difference
                total = i - j + 1
                leq = sum(cnt[:cur_mex+1])
                best = max(best, total - leq)

            res[i] = best

        print(*res)

if __name__ == "__main__":
    solve()
```上面的实现遵循使用每个端点的嵌套扫描直接转换 MEX 定义和权重公式。 它为每个结尾的后缀增量重新计算 MEX`i`，然后减去元素得到权重`<= mex`。 这不是最终的优化版本，但它清楚地展示了结构推理：对于每个固定的右端点，我们评估所有候选左端点，同时动态维护 MEX。 

完全优化的解决方案将避免重建`cnt`重复数组，而是维护最后一次出现和值频率的全局结构，将内部循环转变为摊销常数或对数工作。 

## 工作示例

 考虑数组`[2, 0, 3, 0, 1]`。 

在`i = 0`, 只有子数组`[2]`存在。 它的 MEX 是`0`，因此权重计算的元素大于`0`，即`1`。 但由于没有更小的稳定子阵列可以改善这一点，所以答案是`0`。 

在`i = 2`，数组是`[2, 0, 3]`。 我们评估后缀：

 | 我| 子数组 | 墨西哥 | 重量 |
 | --- | --- | --- | --- |
 | 2 | [3] | 0 | 1 |
 | 1 | [0,3]| 1 | 1 |
 | 0 | [2,0,3]| 1 | 2 |

 最好的是`2`，来自`[2,0,3]`。 

这表明，包含更多元素既可以减少 MEX，又可以增加超出 MEX 的元素数量，而最佳选择是在覆盖小值和积累大值之间取得平衡。 

现在考虑`[0, 1, 2, 3, 5, 4]`。 

在每一步中，前缀逐渐完成集合`{0,1,2,...}`所以MEX稳步增长。 一旦 MEX 达到`k`, 元素大于`k`贡献更显着，并且最佳子数组始终是完整前缀，证明了这种特殊情况下的单调增长。

 ## 边缘情况

 完全为零的数组使 MEX 固定在`1`对于每个子数组。 该算法自然地评估每个后缀并发现没有元素超过`1`，因此每个候选权重为零。 

像这样的排列`[0,1,2,...,n]`为前缀生成严格递增的 MEX。 每个包含完整前缀的后缀都会最大化权重，因为每个新元素都会以可预测的方式增加大于当前 MEX 阈值的值的计数。 

具有重复大值但缺少小值的数组，例如`[5,5,5,0]`，揭示了 MEX 的非单调行为。 前`0`包括在内，MEX 是`0`重量是`0`。 包括后`0`, MEX 跳转到`1`，突然间所有`5`s 有助于体重。 最优子数组发生巨大变化，这就是局部贪婪扩展不够充分的原因。
