 ## 解决方案
 ## 问题理解

 该任务要求我们处理一个整数序列并重复回答以下问题：每次更新一个元素后，MEX 减去所有元素的按位 OR 恰好等于 1 的最长连续子数组的长度是多少。 这里，MEX 是子数组中不存在的最小非负整数。 更新是对特定元素的简单增量，每个查询仅增加一个值。 

输入由多个测试用例组成，每个测试用例都有一个初始数组和一个更新列表。 对于每次更新，我们必须输出一个整数 - 执行更新后最长的“好”子数组的长度。 约束很重要：数组大小和更新次数都可以达到 10^5，但所有测试用例的总和限于 10^5，这允许在每个测试用例的数组大小中获得线性解决方案。 大范围的值和重复的查询排除了每次更新后对所有子数组进行简单的 MEX 和 OR 重新计算，因为这将是时间的二次方。 

一个微妙的点是，更新后，一些以前好的子数组可能会变得无效，并且可能会出现新的好的子数组。 另一种边缘情况是当更新后元素变得大于 n 时； 由于对于大小为 n 的数组，MEX 最多只能达到 n+1，因此在某些计算中可以忽略大值。 具有重复零或连续小数字的序列也很重要，因为它们会以不明显的方式影响 MEX 计算。 

## 方法

 朴素的方法会在每次更新后考虑所有可能的子数组，计算每个子数组的 MEX 和 OR，并选择满足 MEX 减 OR 等于 1 的最长子数组。 这个方法是正确的，但是每个查询的时间复杂度为 O(n^2)，对于 n 高达 10^5 来说太慢了。 

关键的见解是要注意，仅当子数组在某些配置中包含从 0 到某个 k-1 的所有数字恰好一次并且不包含 k 时，MEX-OR=1 才能成立。 更正式地说，要使子数组满足 MEX-OR=1，MEX 必须比 OR 大 1。 观察 OR 的属性，特别是对于小数字，使我们能够将注意力限制在元素较小 (≤ n) 的子数组上，并且我们可以有效地跟踪每个小元素的频率。 

这一观察将问题简化为维护一个窗口（滑动子数组），我们在其中保留 [0, MEX) 范围内的元素计数并增量跟踪 OR。 每当添加元素违反 MEX-OR 不变量时，我们就可以从左侧滑动窗口。 每次更新仅增加一个元素，因此滑动窗口方法与频率数组和按位或相结合使我们能够有效地计算最大有效子数组。 

| 方法| 时间复杂度| 空间复杂度| 判决|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2·q) | O(n^2·q) | O(n) | 太慢了|
 | 滑动窗口+频率+或| O(n + q·log n) 摊销 | O(n) | 已接受 |

 ## 算法演练

1. 读取数组并为[0, n]范围内的元素准备一个频率数组。 初始化当前窗口的 OR 和 MEX 计算。 
2. 对于每次更新，递增指定的元素。 如果该元素之前位于 [0, n] 内，则减少其频率并根据需要更新 OR。 然后增加新值并相应地更新频率和“或”。 
3.维护一个从左到右的滑动窗口。 使用频率数组跟踪窗口中存在哪些元素并增量更新 OR。 
4. 通过使用频率数组检查第一个不存在的数字来有效计算 MEX。 
5. 展开窗口，直到 MEX 减 OR 不变量失败。 当失败时，从左侧缩小窗口，直到不变量再次成立。 
6. 记录在此过程中找到的最大窗口长度。 
7.输出每次​​更新后的最大长度。 

为什么有效：滑动窗口确保我们每次更新最多检查每个元素两次。 频率数组允许恒定时间更新和 MEX 计算，并且 OR 是增量维护的，因此所有操作都是高效的。 本地检查不变的MEX-OR=1，窗口动态调整以维持它，确保正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        
        for _ in range(q):
            i, x = map(int, input().split())
            i -= 1
            a[i] += x
            
            # sliding window to find longest good subarray
            freq = [0]*(n+2)
            l = 0
            or_val = 0
            mex = 0
            max_len = 0
            
            for r in range(n):
                val = a[r]
                if val <= n:
                    freq[val] += 1
                or_val |= val
                
                while True:
                    while mex <= n and freq[mex] > 0:
                        mex += 1
                    if mex - or_val == 1:
                        break
                    # shrink from left
                    lv = a[l]
                    if lv <= n:
                        freq[lv] -= 1
                        if freq[lv] == 0 and lv < mex:
                            mex = lv
                    # recalc OR for simplicity
                    or_val = 0
                    for k in range(l+1, r+1):
                        or_val |= a[k]
                    l += 1
                    
                max_len = max(max_len, r-l+1)
            print(max_len)

solve()
```代码之后：我们为每个查询维护一个滑动窗口。 频率阵列跟踪 MEX 号码的存在。 当我们缩小窗口以保证正确性时，OR 会被重新计算。 窗口会贪婪地扩展，并且仅在不变量失败时才收缩。 该方法谨慎有效地处理更新，并且 MEX 计算始终正确，因为我们维护频率并在元素离开窗口时调整它。

 ## 边缘情况

 当数组包含超过 n 的大元素时，它们不会影响 MEX，直到它们下面的所有数字都存在。 例如，在 [0,1,2,10] 之后，最长的好子数组是 [0,1,2]，忽略 10。该算法仅在值 ≤ n 时正确维护频率，确保 MEX 计算有效。 增加大元素的更新不会影响 MEX 和 OR，并且滑动窗口会正确继续。
