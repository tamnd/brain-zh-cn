 ## 解决方案
 ## 问题理解

 卷轴包含一系列十进制数字。 通过给出其左侧和右侧位置来选择卷轴的片段。 对于该片段，我们查看两个不同位置的每个有序对。 第一个位置的数字形成十位数字，第二个位置的数字形成个位数字，从而创建一个两位数。 片段所需的值是所有这些数字的总和。 

任务是快速回答许多独立的片段查询。 对于每个查询`[l, r]`，我们需要从位置输出子串的势`l`定位`r`。 

序列长度和查询次数均达到`100000`。 这立即排除了处理每个查询中的每对位置。 长度的片段`k`包含`k * (k - 1)`有序对，因此直接模拟每个查询将花费二次时间。 和`100000`查询时，即使是中等大小的片段也会导致数十亿次操作。 

主要的挑战不是对枚举本身，而是认识到每个位置都以完全相同的方式做出贡献。 一旦理解了单个数字的贡献，每个查询就可以简化为一个简单的范围和。 

一些边缘情况可能会破坏过于字面地遵循对定义的实现。 具有一位数字的片段不包含有效的对。 例如：```
Input:
1
5
1
1
1

Output:
0
```粗心的解决方案可能会将数字视为构成数字`55`，但是两个位置一定不同，所以没有数字可以相加。 

另一个常见的错误是忘记这些对是有序的。 例如：```
Input:
2
78
1
1
2

Output:
165
```有效数字是`78`和`87`，不仅`78`。 忽略相反的顺序给出的答案太小。 

最后的边缘情况是具有重复数字的子字符串：```
Input:
3
111
1
1
3

Output:
44
```有六个有序对，每对都会创建一个数字`11`，所以总计为`66`？ 不，这暴露了一个常见的计数错误：配对计数是正确的，但公式必须单独考虑每个位置的贡献。 正确的计算是`11 * (3 - 1) * (1 + 1 + 1) = 66`。 正确的输出是：```
66
```仅计算不同数字对的实现在这里会失败，因为重要的是位置，而不是数字值。 

## 方法

 一个简单的解决方案将独立处理每个查询。 对于一段长度`k`，我们可以枚举每个有序的位置对，计算两位数，并将其添加到答案中。 这是正确的，因为它直接遵循定义。 然而，对的数量是`k(k - 1)`。 在最坏的情况下，查询覆盖整个字符串`100000`数字几乎需要`10^10`结对操作，这远远超出了可用时间。 

关键的观察是我们不需要知道各个对。 考虑一个片段`k`数字，并令其所有数字之和为`S`。 

选择任意位置。 如果它的数字变成十位数字，则它与其他所有位置一起使用，因此它出现在`k - 1`数字。 它在该角色中的贡献是：`10 * digit * (k - 1)`相同的数字也可以成为每个其他位置的个位数字，贡献：`digit * (k - 1)`一位数合计贡献：`11 * digit * (k - 1)`由于每个数字的行为相同，因此整个段的答案是：`11 * (k - 1) * S`现在每个查询只需要两个值：段长度和段中的数字总和。 长度可以从边界直接得知，并且可以使用前缀和来回答数字和。 

暴力解决方案之所以有效，是因为它明确地构建了每个可能的数字。 它失败是因为它多次重复相同的贡献计算。 上面的观察将所有这些对压缩成一个算术公式。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个查询 O((r-l+1)^2) | O(1) | O(1) | 太慢了|
 | 最佳| O(n) 预处理后每个查询的 O(1) | O(n) | 已接受 |

 ## 算法演练

 1. 在卷轴的数字上构建一个前缀和数组。 索引处的值`i`存储第一个的总和`i`数字，允许通过减法找到任何段的总和。 这消除了再次扫描查询段的需要。 
2. 对于每个查询`[l, r]`，计算段长度为`r - l + 1`。 这告诉我们有多少个位置可以与每个选定的数字配对。 
3. 使用前缀和求该段的数字和：`prefix[r] - prefix[l - 1]`。 
4. 应用公式`11 * (length - 1) * digit_sum`并输出结果。 因素`length - 1`表示每个数字可以与另一个位置配对的次数，而因子`11`结合了其十和个的贡献。 

为什么它有效：

 对于查询段中的每个数字，都恰好有`length - 1`其他职位的选择。 当数字是一对中的第一个位置时，它的贡献是其值的十倍。 当它处于第二位置时，贡献一次它的价值。 因此，一个数字的总贡献是`11 * digit * (length - 1)`。 将所有数字相加得出`11 * (length - 1) * sum_of_digits`，这正是所需的电势。 由于前缀和给出了每个查询范围的精确数字和，因此算法始终计算与直接定义相同的值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    prefix = [0] * (n + 1)
    for i, ch in enumerate(s):
        prefix[i + 1] = prefix[i] + (ord(ch) - ord('0'))

    q = int(input())
    ans = []

    for _ in range(q):
        l = int(input())
        r = int(input())

        length = r - l + 1
        digit_sum = prefix[r] - prefix[l - 1]

        ans.append(str(11 * (length - 1) * digit_sum))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```前缀数组是用一个额外元素构建的，以便从位置开始的范围`1`自然有效。 对于查询，`prefix[r] - prefix[l - 1]`给出所要求数字的总和。 

查询长度计算使用输入中从一开始的位置。 减一在`(length - 1)`是必要的，因为数字不能与其自身配对。 这是该问题中最常见的差一错误。 

Python 整数不会溢出，但最大答案可能很大。 表达式大致可以达到`11 * 100000 * 900000`，所以使用普通的整数运算就足够了。

 ## 边缘情况

 对于单位置段，例如：```
1
5
1
1
1
```前缀和给出的数字和为`5`，长度为`1`。 乘数变为`length - 1 = 0`，所以答案是正确的`0`。 该算法从不尝试创建无效的对。 

对于有序对的情况：```
2
78
1
1
2
```段长度为`2`数字和是`15`。 公式给出`11 * 1 * 15 = 165`，其中包括`78`和`87`。 该算法通过十位和个位贡献自动处理顺序。 

对于重复的数字：```
3
111
1
1
3
```段总和是`3`长度是`3`。 每个位置参与两对，每次参与贡献其数字值的十一倍。 公式给出`11 * 2 * 3 = 66`，匹配六个生成的数字。 

对于零：```
5
10203
1
1
5
```数字和是`6`长度是`5`。 答案是`11 * 4 * 6 = 264`。 零数字没有任何贡献，但它们仍然占据位置并影响其他数字拥有的伙伴数量。 该公式正确地包含了它们，因为它基于位置，而不仅仅是非零数字。
