 ## 解决方案
 ## 问题理解

 我们正在使用由两个参数定义的非标准时钟系统：一天中的小时数`h`以及一小时内的分钟数`m`。 时间片刻是成对给出的`(x, y)`在哪里`x`是当前时间并且`y`是当前分钟，其中`0 ≤ x < h`和`0 ≤ y < m`。 

从这个开始时刻开始，时间通常一分钟一分钟地前进，在`m`分钟，然后在`h`小时。 换句话说，时钟的行为就像一个长度周期`h · m`分钟。 

该任务定义了一个关于时间的简单函数：分别取小时和分钟的十进制表示，将所有数字相加，并将该值称为时间的“数字和”。 例如，时间`07:05`有数字和`0 + 7 + 0 + 5 = 12`。 

我们被要求确定从给定的开始时间到我们第一次到达数字总和等于开始时刻的数字总和的时刻需要多少分钟。 

关键细节是时间是循环的。 后`h · m`分钟，我们返回到相同的状态，因此任何搜索自然都会对这段时间取模。 

一个天真的解释表明我们可能需要向前模拟，直到找到匹配项，但循环长度可以大到`10^4`或更多，并且可能有多个测试用例。 对于模拟来说，这看起来仍然足够小，但需要更严格的解决方案。 

当答案是时，就会出现微妙的边缘情况`0`，表示开始时间已经满足条件。 另一个是循环结束时，因此第一个有效时间可能发生在第二天，即使它在线性扫描中“更早”。 

## 方法

 暴力破解的想法很简单：计算开始时间的数字和，然后重复将时钟前进一分钟，每次重新计算数字和，直到再次与原始值匹配。 由于系统会重复以下操作`h · m`步骤，这保证了终止。 

每个步骤花费恒定的时间，因此每个测试的最坏情况复杂度是`O(h · m)`。 在多个测试用例中，如果`h, m ≤ 100`，但是当我们被迫扫描每个查询的几乎整个周期时，这就变得很浪费。 

重要的观察是，我们没有被要求做任何结构性的事情，比如最小化或优化选择。 我们只需要沿着确定性循环第一次返回到固定条件的时间。 这立即将问题减少到扫描长度的圆形数组`h · m`。 不需要高级数据结构或前缀技巧，因为每个状态仅取决于其自己的数字和。 

我们可以通过将每次映射到单个整数索引来提高实现的清晰度`[0, h·m - 1]`。 来自一个州`t`，下一个状态是`(t + 1) mod (h·m)`，我们可以通过除法和取模来计算小时和分钟。 这使转换变得简单，并避免手动处理进位逻辑。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| --- | --- | --- |
 | 暴力模拟| 每次测试 O(h·m) | O(1) | O(1) | 已接受 |
 | 线性循环扫描（索引）| 每次测试 O(h·m) | O(1) | O(1) | 已接受 |

 除此之外没有渐近改进，因为该过程本身是有限循环上的简单遍历。 

## 算法演练

 1.计算起始时间的数字和`(x, y)`并将其存储为`target`。 这个值永远不会改变，并且作为我们想要再次达到的条件。 
2. 将当前时间转换为单个整数`cur = x * m + y`。 这种线性化使得时间进展变得微不足道。 
3. 预先计算任意数字的数字和`(hour, minute)`按需配对。 每次评估仅需要将整数转换为数字，这是给定有界约束的恒定时间。 
4. 启动一个最多运行的循环`h * m`步骤。 在每一步中，计算当前`(hour, minute)`从`cur`使用除法和取模，然后计算其数字和。 
5. 如果数字和匹配`target`，返回自开始以来所采取的步数。 
6. 否则，增加`cur`乘以一（模`h * m`）并继续。 
7. 如果在返回起始状态之前没有找到匹配项，则答案为`0`，因为初始状态已经满足循环保证。 

### 为什么它有效

 时间系统形成一个长度有向的循环`h · m`，其中每个节点到下一分钟正好有一个传出边。 因为我们按顺序遍历循环，所以在重复之前每个可能的时间配置都会被访问一次。 数字和条件是在每个节点上独立评估的，因此我们第一次遇到匹配值必然是向前推进中的最早有效时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def digit_sum(x, y):
    return sum(map(int, str(x))) + sum(map(int, str(y)))

def solve():
    h, m, x, y = map(int, input().split())

    start_sum = digit_sum(x, y)
    start = x * m + y
    total = h * m

    cur = start
    for step in range(total):
        hour = cur // m
        minute = cur % m

        if digit_sum(hour, minute) == start_sum:
            print(step)
            return

        cur = (cur + 1) % total

    print(0)

if __name__ == "__main__":
    solve()
```该解决方案首先读取时钟配置并计算初始时间的数字和。 然后，时间被扁平化为单个整数，以便前进一分钟只是模块化环绕的增量。 

在循环内部，我们从线性索引重建小时和分钟。 这避免了维护单独的状态变量并保证了转换的正确性。 每一步都会重复数字和检查，一旦与原始值匹配，我们就会返回所采取的步数。 

一个微妙的点是处理答案为零的情况。 循环结构已经检查了初始状态`step = 0`，因此立即返回正确地涵盖了这种情况。

 ## 边缘情况

 一种边缘情况是起始时间已经满足数字和条件。 例如，在一个小时钟中`h = 2, m = 3`，开始于`0:00`，数字和为`0`，以及步骤中的第一个检查`0`立即返回`0`。 

另一种情况是正确答案需要环绕循环。 认为`h = 2, m = 3`，开始于`1:02`。 数字和可能直到移动之后才匹配`1:00`,`1:01`,`1:02`环绕后再次。 该算法正确地处理了这个问题，因为它迭代了完整的`h · m`循环。 

最后一种微妙的情况是一个周期中存在多个有效时刻。 该算法始终返回遇到的第一个，因为它按严格的时间顺序扫描而不会跳过状态，从而确保正确性而不需要额外的簿记。
