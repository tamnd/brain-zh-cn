 ## 解决方案
 ## 问题理解

 我们有一个仅由字符组成的字符串`1`和`2`。 金额`1`字符数与数量完全相同`2`人物。 仅当相同的字符永远不会彼此相邻时，门才是稳定的，这意味着最终的字符串必须像这样交替`121212...`或者`212121...`。 

唯一允许的操作是交换两个相邻的字符。 每个相邻的交换通过将一个字符向左或向右移动一位来更改字符串的顺序。 任务是找到将原始字符串转换为任何有效的交替字符串所需的最小交换次数。 

输入大小可达100000个字符。 这立即排除了重复搜索放错位置的字符并在嵌套循环中通过多次单独交换移动它的模拟，因为此类方法可能会达到二次时间。 拥有100000个职位，`O(n^2)`在最坏的情况下，算法需要大约 10^10 次操作，这远远超出了一秒的限制。 

当字符串已经满足条件时，当两种交替模式中只有一种可能时，以及当存在长的相同字符块时，会出现主要的边缘情况。 例如，对于：```
2
12
```答案是`0`。 总是试图构建的粗心实现`1212...`不检查其他模式仍然可以在这里工作，但在其他模式更便宜的情况下可能会失败。 

为了：```
4
2112
```答案是`1`。 换中间的`11`给出`2121`。 仅计算相邻坏对并假设每个此类对都需要交换的解决方案可能会得到错误的结果，因为一次交换可以解决多个未来冲突。 

为了：```
8
22221111
```答案是`6`。 最优目标是`21212121`或者`12121212`。 字符必须相互交叉，并且成本取决于位置之间的距离，而不仅仅是无效子串的数量。 

## 方法

 一个简单的想法是实际执行交换，直到字符串变成交替的。 我们可以扫描字符串，找到当前字符与所需字符不同的第一个位置，找到包含所需字符的后续位置，并将其向左移动并与相邻的交换位置。 这是正确的，因为每个相邻的移动恰好是一个允许的操作。 然而，在像这样的字符串上`222...111...`，在一个大块上移动每个角色需要大量的交换，而模拟本身会执行所有这些交换。 操作次数可以成二次方。 

关键的观察是我们不需要模拟交换。 每个需要移动的角色都将其移动距离贡献给答案。 如果我们决定最终的交替模式，我们确切地知道哪些位置应该包含`1`人物。 我们可以比较当前的位置`1`具有这些目标位置的字符。 

假设当前`1`职位是`a[0], a[1], ...`和目标`1`职位是`b[0], b[1], ...`。 因为两个数组都已排序，所以匹配第一个当前数组`1`与第一个目标`1`，第二个与第二个，依此类推给出最小的总运动。 总和`abs(a[i] - b[i])`计算有多少个位置`1`角色必须移动，但每次交换都会移动一个`1`和一个`2`同时，因此交换次数是该值的一半。 

最终的模式只有两种可能。 我们计算成本`1212...`和`2121...`并取较小的一个。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.收集角色所在的位置`1`出现在原始字符串中。 由于所有目标字符串的数量完全相同`1`字符，这个列表大小足以描述每个可能的目标。 
2. 检查目标模式在哪里`1`应使用从零开始的索引放置在每个偶数索引处。 比较当前`1`位置与这些所需位置并添加它们的移动距离。 将结果除以二即可得到交换次数。 
3. 检查相反的模式`1`应放置在每个奇数索引处。 同样的计算给出了第二种可能的最终安排的成本。 
4. 输出两个成本中较小的一个。 由于每个有效的最终字符串必须是这两种交替模式之一，因此无需考虑其他排列。 

为什么有效：在相邻交换期间，相同字符的顺序不会改变。 第一个`1`原始字符串中从左边开始必须成为第一个`1`在目标字符串中，因为将其分配到其他任何位置都会使其行进更远并增加总移动量。 同样的论点适用于以下每一个`1`。 所有运动的总和`1`字符数等于交换次数的两倍，因为每个交换交换一个`1`与一个`2`并恰好移动一`1`由一个位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    ones = [i for i, c in enumerate(s) if c == '1']

    def cost(start):
        total = 0
        for idx, pos in enumerate(ones):
            target = start + 2 * idx
            total += abs(pos - target)
        return total // 2

    print(min(cost(0), cost(1)))

if __name__ == "__main__":
    solve()
```名单`ones`存储所有的当前位置`1`人物。 这是足够的信息，因为`2`字符由剩余位置自动确定。 

辅助函数接收第一个位置，其中`1`应该出现。 值为`0`代表`121212...`，而值为`1`代表`212121...`。 目标位置是通过以下方式生成的`start + 2 * idx`。 

除以二是微妙的部分。 总和衡量了总共有多少步`1`人物旅行。 单个相邻交换移动一个`1`一个位置，也移动一个`2`相反方向的一个位置，因此移动算作`1`字符数正好是交换次数的两倍。 

没有二分查找或模拟，因此该算法仅扫描字符串固定次数。

import sys
import io

def solution(data: str) -> str:
    sys.stdin = io.StringIO(data)
    input = sys.stdin.readline

    n = int(input())
    s = input().strip()

    ones = [i for i, c in enumerate(s) if c == '1']

    def cost(start):
        total = 0
        for i, pos in enumerate(ones):
            total += abs(pos - (start + 2 * i))
        return total // 2

    return str(min(cost(0), cost(1))) + "\n"

 ## 边缘情况

 对于已经交替的情况：```
2
12
```的立场`1`是`[0]`。 第一个模式想要一个`1`在位置`0`，给予零运动。 第二个模式希望它位于位置`1`，进行一个动作。 最小值是`0`，因此该算法保持字符串不变。 

对于长块的情况：```
8
22221111
```这`1`职位是`[4,5,6,7]`。 对于目标`12121212`，所需的位置是`[0,2,4,6]`。 动作是`4 + 3 + 2 + 1 = 10`, 给予`5`互换。 对于目标`21212121`，所需的位置是`[1,3,5,7]`, 给予动作`3 + 2 + 1 + 0 = 6`，即`3`互换。 该算法返回较小的值。 

对于相邻冲突重叠的情况：```
4
2112
```有一个`11`在中间。 最佳的改变是不要单独修复每个坏对。 目标`2121`需要将一个字符移动一个位置，因此计算出的移动总共是两个位置，答案是交换一个位置。 该算法捕获了这一点，因为它测量最终位移而不是计算局部模式。
