 ## 解决方案
 ## 问题理解

 我们正在使用两个长度相等的整数数组。 每个位置都会独立地产生总“误差”，其中索引的误差是该索引处两个值之间的差的平方。 总成本是所有指数的平方差之和。 

我们可以修改数组，但只能以非常有限的方式进行。 我们必须准确执行`k1`对数组元素进行单位递增或递减操作`A`，并且准确地说`k2`对数组进行此类操作`B`。 每个操作都会将单个元素更改 +1 或 -1。 

目标是将这些单位移动分布在元素之间，以便在使用所有操作后，相应元素之间的平方差之和尽可能小。 

重要的结构是每次移动仅将一个数组元素更改 1，并且每个更改单位仅影响一个平方项。 除了通过全球预算变动之外，指数之间没有相互作用，因此问题归结为决定将这些有限的调整花在哪里。 

限制很小：`n ≤ 1000`和总运营`k1 + k2 ≤ 1000`。 这立即表明解决方案可以模拟单独的调整，而不是依赖于大型状态的重型优化结构。 然而，对所有元素的所有操作分布进行简单搜索仍然会组合爆炸，因为每次移动都可以到达任一数组中的任何索引。 

一些边缘情况值得尽早隔离。 

当所有对应值都相等时，初始误差为零。 如果还有剩余操作，则仍必须使用它们，因此阵列可能会再次偏离，从而可能增加最终误差。 总是减少差异的粗心贪婪方法会错误地假设答案为零。 

当一个数组具有所有操作而另一个数组没有时，所有移动都被强制放入一个结构中。 例如，如果`A = [1,1]`,`B = [100,100]`，并且仅`A`允许移动，所有操作必须在`A`即使他们在以后减少之前暂时增加了误差。 

最后，由于成本是二次方的，减少大差异比减少小差异更有价值。 任何将每个单位改进视为平等的解决方案都是不正确的。 

## 方法

 一个蛮力的想法是考虑每个可能的操作序列：在每个步骤中，在任一数组中选择一个索引，并决定是递增还是递减它。 这创建了一个大致的分支因子`2n`每个操作的选择和深度可达`k1 + k2`，这导致了指数级的可能性。 即使进行积极的修剪，这也是不可行的，因为状态的数量随着`(2n)^(k1+k2)`。 

一旦我们根据差异重写问题，结构就变得易于管理。 

让`d[i] = a[i] - b[i]`。 总误差只是以下的总和`d[i]^2`。 每个操作对`A`增加或减少一些`d[i]`减 1，并且每次操作`B`也改变了一些`d[i]`反方向加1。 在这两种情况下，重要的是我们可以在每个操作中将某些选定差异的绝对值减少 1，或者如果强制的话可能会增加它。 

所以整个问题变成：我们有一组绝对差异，并且我们可以准确地应用`k = k1 + k2`单元操作，每个操作将一个选定的差异调整±1。 我们的目标是最小化最后的平方和。 

关键的观察是局部的：如果我们想减少总平方和，我们总是想减少当前最大的绝对差，因为减少的边际增益`x`到`x-1`是`x^2 - (x-1)^2 = 2x - 1`，越大则越大`x`。 这种贪婪的“总是修复最大的差距”策略是最优的。 

实现此目的的标准方法是在最大堆中维护所有绝对差异。 每个操作提取最大值，将其减 1，如果仍然为正则将其推回原处。 所有运算结束后，我们进行平方和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(1) | O(1) | 太慢了 |
 | 堆贪婪 | O((n + k) log n) | O((n + k) log n) | O(n) | 已接受 |

 ## 算法演练

 我们把问题转化为不断缩小绝对差异。 

### 步骤

 1. 计算初始差分数组`d[i] = |a[i] - b[i]|`。 

这隔离了每个索引，因为除了通过选择之外，操作永远不会跨索引交互。 
2. 全部插入`d[i]`进入最大堆。 

堆总是暴露最大的剩余差异，这是进行操作最有价值的地方。 
3.让`k = k1 + k2`。 对于每个`k`操作：

 提取最大差异`x`从堆中。 

如果`x > 0`，将其替换为`x - 1`并将其推回去。 

如果`x == 0`，将其推回原样。 

这可确保按照问题的要求使用每个操作。 
4. 所有运算完成后，通过求和计算出最终答案`x^2`覆盖所有堆元素。 

这是最终的平方误差。 

### 为什么它有效

 任何时候，考虑两个差异`x ≥ y`。 减少`x`平方和的减少量比减少量要大得多`y`，因为增益是`2x - 1`相对`2y - 1`。 由于每个操作都是独立的并且具有相同的成本，因此任何最优策略都必须始终优先考虑当前的最大差异。 这种交换论点确保了任何在存在较大值时花费较小值的操作的解决方案都可以通过交换这些操作来改进，而不会恶化可行性或总成本。 该不变量保证了堆贪婪过程与最佳操作序列相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, k1, k2 = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    k = k1 + k2

    # max heap via negative values
    heap = []
    for i in range(n):
        heapq.heappush(heap, -(abs(a[i] - b[i])))

    for _ in range(k):
        x = -heapq.heappop(heap)
        if x > 0:
            x -= 1
        heapq.heappush(heap, -x)

    ans = 0
    while heap:
        x = -heapq.heappop(heap)
        ans += x * x

    print(ans)

if __name__ == "__main__":
    solve()
```该实现依赖于使用负数模拟的最大堆。 每个操作都被显式模拟，这是可行的，因为操作总数以 1000 为界。最后的循环直接计算平方和。 

一个微妙的细节是，我们总是将值推回到堆中，即使它为零。 这避免了必须跟踪堆大小一致性并在整个过程中保持堆元素数量稳定。

 ## 边缘情况

 当所有差值均为零时，堆中仅包含零。 该算法仍然执行所有操作，重复选择零并保持不变。 例如：

 输入：```
1 3 0
5
5
```堆是`[0]`。 3个操作均弹出0并原样推回，所以最终答案不变`0`。 这符合操作是强制性的但不能进一步减少错误的约束。 

当只有一个元素时，所有操作都集中在该单一差异上。 如果差异较大，则逐渐减小； 如果操作超过该值，则其余部分无效。 这种行为是从堆进程中自然出现的，无需特殊的外壳。
