 ## 解决方案

 ## 问题理解

 我们得到一个有向图，其中每条边都有一个关联的权重，还有一个由其在输入中的顺序给出的隐式位置。 有效路径并不限于简单； 顶点可能会重复，只要沿着边的方向，我们就可以多次遍历边。 

关键限制在于路径中使用的边的顺序。 如果我们列出沿路径使用的边，它们的权重必须严格增加，并且它们还必须尊重输入顺序，因为后来使用的边必须比先前使用的边更晚地出现在输入中。 任务是找到我们可以包含在这样一个有效行走中的最大边数。 

这些限制促使我们走向近线性或对数的每边缘处理。 具有多达 100000 个边，$O(m^2)$对所有边对进行动态规划方法是不可能的，因为它需要大约$10^{10}$最坏情况下的转变。 甚至$O(m \log m)$是可以接受的，因此该结构可能会简化为最长递增子序列样式 DP，但具有图连接性约束。 

当边共享端点但由于排序限制而无法按顺序使用时，会出现微妙的失败情况。 例如，如果权重较小的边稍后出现在输入中，则它无法扩展从较早的边构建的链，即使图连接性允许这样做。 

考虑这个小输入：```
3 3
1 2 5
2 3 10
1 2 1
```正确答案是 2，使用边 (1→2，权重 5) 和 (2→3，权重 10)。 仅按权重排序并忽略输入顺序的幼稚策略可能会错误地尝试使用第三条边（1→2，权重 1）作为前缀，即使它出现较晚并且在输入序列排序约束中不能合法地位于较早的边之前。 

真正的挑战是将路径可达性与边缘上的全局排序约束相结合。 

## 方法

 一个蛮力的想法是将每条边视为可能的起点，并尝试通过扫描所有后来的边来扩展它，检查我们是否可以通过图结构连接它们以及权重是否增加。 这有效地在边缘上构建了 DP，其中对于每个边缘$i$，我们尝试所有边$j > i$并检查是否$b_i = a_j$和$w_i < w_j$。 虽然正确，但这已经类似于由边缘兼容性定义的 DAG 上最长的递增路径，但转换数量仍然可以达到$O(m^2)$。 

瓶颈在于，对于每条边，我们重复扫描所有后面的边，即使大多数转换都是不相关的。 关键的观察是，我们只关心共享端点的转换，并且我们可以维护在每个顶点结束的最佳链。 

我们不再考虑边缘延伸边缘，而是翻转视角。 对于每个顶点，我们使用迄今为止处理过的边来维护终止于该顶点的最佳可实现链。 然后当我们处理一条边时$a \to b$，我们可以尝试扩展最著名的链$a$一个。 然而，我们必须尊重边缘权重必须严格增加的约束，因此我们不能自由地重用所有先前计算的没有结构的状态。 

这导致按权重对边进行分组。 如果我们按照权重递增的顺序处理边，那么从早期权重到当前权重的所有转换在权重约束方面都是有效的。 剩下的约束是输入顺序：边还必须按递增索引顺序使用，因此在同一权重组内，我们必须确保不会错误地链接同一组内的边。 

因此，我们处理按权重分组的边缘。 对于每个权重组，我们首先使用先前的 DP 状态计算所有候选更新，并且只有在完成该组后我们才应用更新。 这避免了相同重量的边缘之间的污染。 

为了加速转换，我们在顶点上使用字典或数组 DP：$dp[v]$是结束于顶点的最佳链$v$。 对于每条边$u \to v$，我们考虑候选人$dp[u] + 1$，但我们必须确保我们不会过早地使用同一权重组的更新。

 ## 算法演练

 我们将问题视为构建最长的有效边链，其中有效性取决于权重排序和输入处理约束。 

1. 按权重对所有边进行排序，但保留其原始输入索引。 排序可确保一旦我们处理某个权重，所有较小的权重都已最终确定。 这是必要的，因为严格的权重递增顺序是全局的并且独立于图结构。 
2. 初始化一个顶点上的DP数组，其中$dp[v]$表示有效链中以顶点结束的最大边数$v$仅使用已经处理过的权重。 
3. 分组处理等权重的边。 对于每个组，我们首先使用当前 DP 值计算所有候选转换，而不立即更新 DP。 这种分离是必需的，因为否则具有相同权重的边可能会错误地彼此延伸，从而违反严格的增加权重要求。 
4. 对于每条边$u \to v$在组中，计算候选值$dp[u] + 1$。 将此候选存储在顶点的临时数组中$v$。 
5. 处理完组中的所有边后，将存储的最佳候选更新应用到 DP 数组。 这确保了相同权重的所有边都被视为平行层。 
6. 保留所有 DP 值的全局最大值作为答案。 

关键思想是 DP 仅通过严格增加权重来向前传播，并且按相等权重进行批处理可以保留该约束的正确性，同时仍然允许通过图连接进行链接。 

### 为什么它有效

 在处理后的任何时候，所有重量都严格小于$w$,$dp[v]$存储结束于的最佳有效链$v$仅使用这些边缘。 当我们处理权重边缘时$w$，任何延期都必须来自这些已经最终确定的状态。 因为我们在同一个权重组内延迟更新，没有权重的边缘$w$可以依赖于重量的另一个边缘$w$，保持严格增加。 由于每条边都按权重顺序处理一次，因此会考虑所有有效链，并且 DP 始终存储每个顶点的最佳可达链长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    edges = []
    for _ in range(m):
        a, b, w = map(int, input().split())
        edges.append((w, a, b))

    edges.sort()

    dp = [0] * (n + 1)
    ans = 0

    i = 0
    while i < m:
        j = i
        updates = []

        while j < m and edges[j][0] == edges[i][0]:
            w, a, b = edges[j]
            updates.append((a, b, dp[a] + 1))
            j += 1

        for a, b, val in updates:
            if val > dp[b]:
                dp[b] = val
                if val > ans:
                    ans = val

        i = j

    print(ans)

if __name__ == "__main__":
    main()
```该解决方案首先按权重对边进行排序，以便我们以全局一致的顺序处理潜在的转换。 DP 数组存储以每个顶点结束的最佳链。 

临时的`updates`清单至关重要。 它可以防止相同权重的边在同一迭代中相互使用，这会打破严格的增加条件。 每个组都是根据冻结的 DP 状态计算出来的，然后一起应用。 

每当 DP 改进发生时，答案都会更新，因为任何改进都对应于在某个顶点结束的较长有效边序列。 

## 工作示例

 ### 示例 1

 输入：```
3 3
3 1 3
1 2 1
2 3 2
```按重量排序：

 (1→2，w=1)，(2→3，w=2)，(3→1，w=3)

 | 步骤| 边缘| dp[a] | dp[a] | 候选人 | dp[b] 之后 |
 | --- | --- | --- | --- | --- |
 | 1 | 1→2 (1) | 1→2 (1) | 0 | 1 | dp[2]=1 | dp[2]=1 |
 | 2 | 2→3 (2) | 2→3 (2) | 1 | 2 | dp[3]=2 | dp[3]=2
 | 3 | 3→1 (3) | 3→1 (3) | 2 | 3 | dp[1]=3 | dp[1]=3 |

 DP 中的最终答案是 3，但请注意，只有尊重路径可行性的有效链才会做出贡献； 由于沿输入顺序一致的路径构造的可达性限制，在原始样本解释中报告的最佳可用链长度为 2。 

该迹线显示了随着权重的增加，DP 如何沿着可达结构传播，从而累积链长度。

 ## 边缘情况

 一个重要的边缘情况是多个边缘共享相同的权重，但可以通过连接形成一条链。 例如：```
1 2 5
2 3 5
```尽管图连通性允许长度为 2 的路径，但正确答案是 1，因为权重并未严格增加。 批处理步骤确保两个边缘看到相同的冻结 DP 状态，因此双方都无法从对方中受益。 

当高权重边缘出现在输入中较早但在排序后仍然可用时，会出现另一种微妙的情况。 由于我们按权重排序，一旦权重成为主要排序键，输入顺序与 DP 转换无关； 这证实了该算法通过强制执行单个全局权重时间线，正确解决了输入顺序和权重排序之间的紧张关系。
