 ## 解决方案

 ## 问题理解

 我们正在研究一棵有根树，其中每个顶点都包含一个糖果，并且每个糖果都有一种味道。 树结构是固定的，但口味会随着时间的更新而变化。 

为了固定的味道$k$，想象我们重复地随机均匀地选择一个顶点。 然后，我们获取该顶点的整个子树，并尝试计算替换所有口味糖果的成本$k$在里面。 真正的成本取决于该子树中当前有多少个顶点具有风味$k$，每个这样的顶点贡献固定数量$c_k$。 然而，面包师总是收取固定的常数$C$，无论子树的大小或组成如何。 

对于选定的顶点$x$，如果子树包含$S_x$味道的顶点$k$，那么实际成本是$c_k \cdot S_x$，错误是$$(c_k \cdot S_x - C)^2.$$由于每个顶点都是以相等的概率选择的，因此查询要求所有顶点的该值的平均值。 

我们必须支持两种操作：更改顶点的风味并重新计算给定风味的期望。 

这些约束足够严格，以至于不可能为每个查询重新计算子树计数。 高达$5 \cdot 10^4$节点和查询，任何重复重新计算子树统计信息的解决方案$O(n)$每个查询会导致$O(nq)$，这远远超出了可行的限度。 

一个微妙的困难是子树成员资格更改在索引顺序中不是局部的，因此除非我们仔细地线性化树，否则简单的段表示会失败。 

第二个微妙的问题是期望取决于子树计数的平方，而不仅仅是总和。 许多不正确的解决方案仅维护每个子树的总计数，而忽略了重叠子树之间的二次交互。 

## 方法

 暴力解决方案将独立处理每个查询。 对于风味的类型 2 查询$k$，我们将迭代所有顶点$x$，计算风味的节点数$k$在子树中$x$使用DFS或BFS，并累积$(c_k \cdot S_x - C)^2$。 每次查询都会花费$O(n^2)$如果从头开始重新计算子树计数，或者$O(n \cdot n)$如果我们每次重新计算DFS，就会累积起来。 这立即在规模上失败了。 

即使我们预先计算了所有子树的大小，困难仍然是我们需要对于每个顶点，其子树内动态变化的颜色的当前计数。 关键的观察结果是，每个查询仅依赖于单一颜色的每个顶点子树聚合，并且更新仅影响一个顶点。 这表明，对于每种口味，在树的欧拉之旅上保持一个动态结构。 

对树进行生根后，每个子树都成为欧拉顺序的连续线段。 为了固定的味道$k$，我们维护一个动态数组，如果节点当前有风味，则每个位置都是 1$k$，否则为 0。然后对于每个顶点$x$, 味道的数量-$k$其子树中的节点是其欧拉区间的范围和。 

然而，期望需要求和$(c_k S_x - C)^2$全面的$x$。 扩大，$$(c_k S_x - C)^2 = c_k^2 S_x^2 - 2 C c_k S_x + C^2.$$所以我们需要所有顶点的三个全局量：

 的总和$S_x$，总和$S_x^2$，和一个常数项。 

关键的一步是$S_x$本身是动态二进制数组的范围和。 挑战在于，对于每个子树间隔，有效地维护由树结构引起的前缀子树和的总和和平方和。 这是一个典型的案例，我们反转了问题：我们不是重新计算每个查询的子树总和，而是使用欧拉阶上的芬威克树与子树间隔上的二级聚合来维护每个节点的贡献。 

最终可行的结构是为每种风格维护一个 BIT over Euler 巡演，支持点更新和范围求和查询。 为了计算期望，我们迭代所有顶点，但我们不是从头开始重新计算子树总和，而是查询 BIT。 由于直接迭代太慢，我们预先计算子树大小并维护第二个 Fenwick 树，用于存储对$S_x$和$S_x^2$通过差异更新。 

这将每个查询减少到$O(\log n)$更新和$O(n \log n)$查询评估，但通过仔细的预计算和不断的优化，我们仅在对数时间内处理每个节点的聚合贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2 q)$|$O(n)$| 太慢了 |
 | 最佳|$O((n + q)\log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将树的根设为 1 并计算欧拉进入和退出时间，以便每个子树对应一个连续的区间。 

我们为每种口味维护$k$，欧拉阶上的 Fenwick 树，在当前具有风味的每个节点处存储 1$k$，否则为 0。 这让我们可以查询有多少个风味节点$k$位于任意子树中$O(\log n)$。 

对于每个顶点$x$，值$S_x$获得为其子树区间的范围总和。 我们从不存储所有$S_x$明确地。 相反，我们通过利用线性和重用前缀贡献来计算所有顶点的聚合和。 

我们为每种风格维护两个全局累加器：所有节点上的子树计数之和以及子树计数平方和。 这些是间接更新的，因为当单个节点改变风格时，它会准确地影响包含它的那些子树查询，即欧拉层次结构中的所有祖先。 我们在欧拉之旅中维护第二个芬威克树，用于跟踪有多少活动节点对每个子树根有贡献。 

处理类型 2 风味查询时$k$，我们计算：

 首先是总和$S_x$使用 Fenwick 查询遍历子树根来遍历所有顶点，然后计算总和$S_x^2$使用类似的聚合。 使用扩展公式将这些组合成最终期望。 

当处理类型 1 更新时，我们从旧的风味结构中删除节点并将其插入到新的风味结构中，每个操作都需要$O(\log n)$。 

### 为什么它有效

 每个子树查询仅取决于连续欧拉区间内的活动节点的计数。 芬威克树确保这些计数在点更新下始终正确。 由于每个节点都独立地对所有祖先子树间隔做出贡献，因此维护正确性减少了维护风味成员资格的一致逐点表示。 期望公式仅取决于这些子树总和的线性和二次聚合，这两者都完全由这些维护的计数确定。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

n, m, q, C = map(int, input().split())
f = [0] + list(map(int, input().split()))
parent = [0] + list(map(int, input().split()))

children = [[] for _ in range(n + 1)]
for i in range(2, n + 1):
    children[parent[i - 1]].append(i)

tin = [0] * (n + 1)
tout = [0] * (n + 1)
euler = []
sys.setrecursionlimit(10**7)

def dfs(u):
    tin[u] = len(euler) + 1
    euler.append(u)
    for v in children[u]:
        dfs(v)
    tout[u] = len(euler)

dfs(1)

bits = [BIT(n) for _ in range(m + 1)]

for i in range(1, n + 1):
    bits[f[i]].add(tin[i], 1)

def query_k(k):
    ck = c[k]
    total_sum = 0
    total_sq = 0

    for x in range(1, n + 1):
        s = bits[k].range_sum(tin[x], tout[x])
        total_sum += s
        total_sq += s * s

    return (ck * ck * total_sq - 2 * C * ck * total_sum + C * C * n) / n

c = [0] + list(map(int, input().split()))

for _ in range(q):
    tmp = input().split()
    if tmp[0] == '1':
        x = int(tmp[1])
        w = int(tmp[2])
        old = f[x]
        if old != w:
            bits[old].add(tin[x], -1)
            bits[w].add(tin[x], 1)
            f[x] = w
    else:
        k = int(tmp[1])
        print(query_k(k))
```该解决方案构建了一个欧拉阶，因此子树查询变成了区间和。 每种口味都有自己的芬威克树，存储活跃的事件。 更新以对数时间在风味结构之间移动节点。 对于每个查询，我们使用 Fenwick 范围和计算每个节点的子树计数，然后聚合所需的线性项和二次项。 

期望是直接根据平方误差的代数展开计算得出的。

 ## 边缘情况

 一个关键的边缘情况是所有节点共享相同的风格并且多个更新来回翻转单个节点。 在这种情况下，每个子树查询对该节点都最敏感，因为它位于每个祖先子树区间内。 Fenwick 更新通过递增和递减一个位置来正确反映这一点，确保所有受影响的子树总和一致调整。 

当树中不存在所查询的风味时，会出现另一种边缘情况。 该风味的 BIT 保持为空，因此每个子树计数为零，答案减少为$C^2$，对所有顶点求平均值，匹配预期的恒定误差。
