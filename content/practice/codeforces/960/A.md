 ## 解决方案
 ## 问题理解

 我们得到一个仅由字符组成的字符串`a`,`b`， 和`c`。 据称该字符串是以一种非常特定的方式构建的：它以一个或多个开头`a`字符，然后是一些`b`附加字符，最后一些`c`字符附加在末尾。 在这三个阶段之后，字符串必须至少包含一个`a`以及至少一个`b`， 尽管`c`可能存在也可能不存在，具体取决于构造规则。 

关键约束不仅与数量有关，还与结构有关。 该字符串必须采用非递减相序：全部`a`先来，然后全部`b`，那么所有`c`。 最重要的是，数量`c`字符数必须等于`a`字符或数量`b`字符（或两者，如果它们相等）。 

任务是确定给定的字符串是否可以通过这样的过程生成。 

输入大小最多为 5000 个字符。 这个值足够小，任何达到大致二次行为的解都可以顺利通过，但问题的结构表明线性扫描就足够了。 由于我们只是验证一个模式而不是构造任何东西，所以我们应该期望 O(n) 检查。 

一个天真的误解是只关注计数。 例如，像这样的字符串`acbbc`具有相同的计数`a`,`b`， 和`c`但由于顺序被破坏而无效。 另一个微妙的失败是假设字符串可以重新排列，但重新排列是不允许的。 

经常破坏错误解决方案的边缘情况包括：

 - 混合订购，例如`aba...`在哪里`b`出现在所有人之前`a`完成了。 
- 缺少必需的段，例如没有`b`根本不。 
- 顺序正确但错误`c`计数，例如`aabccc`在哪里`a=2`,`b=1`,`c=3`，自此无效`c`既不匹配 2 也不匹配 1。 
- 像这样的字符串`aaabbbccc`一切都很干净而且很匹配`a`或者`b`。 

## 方法

 强力解释会尝试将字符串分成三段并检查所有可能的分割点。 对于每个分割`(i, j)`，我们解释`S[0:i]`和大家一样`a`,`S[i:j]`和大家一样`b`， 和`S[j:]`和大家一样`c`，然后验证排序和计数条件。 这需要尝试 O(n²) 次分割，每次验证的成本为 O(n)，在最坏的情况下会导致 O(n³)，即使对于 n = 5000，这也是不必要和浪费的。 

问题的结构消除了猜测分裂点的需要。 该字符串如果有效，则具有严格的单调模式：一旦字符类型发生更改，它就永远不会返回。 这意味着我们可以从左到右扫描并确保转换遵循`a → b → c`仅有的。 同时，我们计算每个字符的出现次数。 

扫描完成后，我们只需要检查两个条件：满足排序约束以及最终计数满足`c == a or c == b`，还有一个额外的隐含要求：`a > 0`和`b > 0`因为构造至少保证其中之一。 

这将整个问题简化为通过不断记账的单次传递。

 ## 算法演练

 1.初始化计数器`ca`,`cb`,`cc`为零。 还跟踪代表我们当前所在块的阶段变量：`0`为了`a`,`1`为了`b`,`2`为了`c`。 
2. 从左到右扫描字符串。 
3. 对于每个字符：

 - 如果是的话`a`，仅当我们仍处于阶段时才有效`0`。 增量`ca`。 
- 如果是的话`b`，我们必须处于阶段`0`或者`1`。 如果我们在舞台上`0`，切换到舞台`1`。 增量`cb`。 
- 如果是的话`c`，我们必须处于阶段`1`或者`2`。 如果我们在舞台上`1`，切换到舞台`2`。 增量`cc`。 

任何违反允许转换的行为都会立即使字符串无效。 
4. 扫描后，确保两者`ca > 0`和`cb > 0`。 
5.最后检查是否`cc == ca`或者`cc == cb`。 

在扫描期间强制转换的原因是为了确保我们永远不会允许`b`在完成所有之前`a`，或一个`c`在完成所有之前`b`。 

### 为什么它有效

 施工过程保证三相单调结构。 任何有效的字符串都必须有一个唯一的分区，分为连续的块`a`， 然后`b`， 然后`c`。 stage 变量恰好强制执行此分区。 由于每个字符在严格的转换规则下都被处理一次且仅一次，因此任何与所需顺序的偏差都会立即检测到。 结构验证后，唯一剩下的自由度是计数`c`，它必须根据构造的定义匹配早期的块大小之一。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()

ca = cb = cc = 0
stage = 0  # 0 = a, 1 = b, 2 = c

valid = True

for ch in s:
    if ch == 'a':
        if stage != 0:
            valid = False
            break
        ca += 1
    elif ch == 'b':
        if stage == 2:
            valid = False
            break
        if stage == 0:
            stage = 1
        cb += 1
    else:  # 'c'
        if stage < 1:
            valid = False
            break
        if stage == 1:
            stage = 2
        cc += 1

if not valid or ca == 0 or cb == 0:
    print("NO")
else:
    print("YES" if (cc == ca or cc == cb) else "NO")
```代码维护了严格的相位变量`stage`它对我们当前允许扩展的段进行编码。 这可以防止非法的向后转换，例如遇到`a`经过一个`b`。 计数器跟踪最终条件所需的准确频率。 

一个微妙的一点是，过渡只会向前推进：一旦我们进入舞台`1`，我们永远不会回去。 这与构建过程的不可逆性相匹配。

 ## 边缘情况

 关键的边缘情况是字符串具有正确的排序但未满足计数约束。 用于输入`aaabbbcccc`，扫描产生`ca=3`,`cb=3`,`cc=4`。 阶段逻辑在结构上接受它，但最终检查拒绝它，因为`cc`都不匹配`ca`也不`cb`。 

另一种边缘情况是过渡发生得太早。 为了`baaa`, 第一个字符`b`力量阶段`1`，但是遇到`a`随后立即违反规则，导致在任何计数事宜之前被提前拒绝。 

最后一种情况是一个最小的有效结构，例如`abc`。 扫描集`ca=1`,`cb=1`,`cc=1`，并且自从`cc == ca == cb`，它被接受，确认最终条件自然地处理了所有三个段的相等性。
