 ## 解决方案

 ## 问题理解

 我们正在使用一个无限完全二叉树，其节点以标准堆顺序标记。 根为 1，每个节点 x 都有子节点 2x 和 2x+1。 这意味着每个节点都对应于从根开始的唯一二进制表示路径，其中向左移动附加 0 位，向右移动附加 1 位。 

不同的是，树不是静态的。 我们可以对与某个给定节点 X 具有相同深度的所有节点执行操作。根据操作的不同，我们要么旋转该级别上的节点标签，要么旋转以这些节点为根的整个子树，这有效地水平移动无限树的整个块，同时保留内部结构。 

最终的查询类型要求在所有转换之后沿着从节点 X 到根的路径的值，并且这些转换可能以复杂的方式排列了级别内的节点。 

输入大小达到 10^5 次操作，节点值达到 10^18，因此我们无法显式模拟树或在每次操作后重建结构。 任何尝试显式跟踪单个节点或整个级别的解决方案都将在内存和时间上失败。 

一个天真的想法是为每个深度维护显式数组。 但深度可以达到 60 左右，因为 2^60 已经超过 10^18。 即使深度很小，每个级别在概念上也可以包含指数数量的节点，从而使得直接存储变得不可能。 

第二个天真的想法是在轮班情况下跟踪每个节点的当前身份。 然而，由于子树移动会影响无限多个后代，因此向下传播更改也是不可行的。 

当混合两种操作类型时，会出现一个微妙的陷阱。 类型 1 仅移动级别内的标签，而类型 2 则移动以该级别上的节点为根的整个子树。 这些是根本不同的行为，混淆它们会导致错误的祖先重建。 例如，在子树移位之后，节点的父节点不再是原始标记中的简单x//2。 

正确的方法必须避免单独跟踪节点，而是以压缩形式维护逐级转换。 

## 方法

 关键的观察是每个节点都属于一个深度，并且每个操作仅影响由 X 确定的单个深度级别。由于深度约为 log2(X)，因此我们只与大约 60 个级别交互。 

我们在概念上将这两个操作分开。 

类型 1 操作是级别内节点标签的循环移位。 这意味着在固定深度 d 处，节点的顺序会旋转。 重要的是，这不会影响父子关系，因为树的结构保持不变。 仅排列该级别的标签。 

类型 2 操作更加微妙。 它在给定级别旋转节点，但也会随之移动整个子树。 这意味着节点与其父节点之间的映射发生了变化，因为父节点位置下的子树的标识发生了变化。 

暴力模拟需要为每个级别维护一个显式的节点列表并在每次转换时更新它，并另外更新类型 2 的父子指针。这将花费 O(N * 级别大小)，这是不可能的，因为级别实际上是无界的。 

关键的见解是我们永远不需要完整的结构。 对于任何节点X，我们只关心它的祖先，它们形成了一条长度最多为60的链。我们可以通过逐级向上行走来重建这条链，纠正每个深度发生的所有变化。

我们没有存储完整级别，而是为每个深度维护两个值：一个表示类型 1 操作的累积循环移位，另一个表示类型 2 操作的累积结构移位。 类型 2 的行为类似于影响父映射的附加偏移量，而类型 1 仅影响该级别的标签解释。 

在回答查询时，我们通过撤消当前深度的两种效果来重复将当前节点映射到其父节点。 这是可行的，因为二叉树结构确保每个节点的父节点仅由其在其级别内的位置确定，并且两个操作都是级别本地的。 

因此，我们将问题简化为维护每个级别的 O(log X) 状态并执行每个查询的 O(log X) 向上跳转。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N * 级别大小) | O（水平尺寸）| 太慢了 |
 | 最佳| O(N log A) | O(N log A) | O(log A) | 已接受 |

 ## 算法演练

 1. 通过重复除以 2 直到达到 1 来计算节点 X 的深度。这定义了我们对涉及 X 的每个查询进行操作的级别。 
2. 维护两个数组shift1[d]和shift2[d]，其中d是深度。 shift1 跟踪由类型 1 查询引起的 d 层节点标签的循环旋转，而 shift2 跟踪由类型 2 查询引起的结构旋转。 这种分离是必要的，因为一个影响标签，另一个影响父映射。 
3. 对于深度 d 处的类型 1 查询，将 K 添加到以该概念级别的大小为模的 shift1[d]。 由于级别是无限的，我们只需要保持相对于遍历的移位，而不是绝对大小。 
4. 对于类型2查询，类似地将K添加到shift2[d]。 这表示子树根在该级别如何旋转，从而更改父子对齐方式。 
5. 要回答类型 3 查询，请从节点 X 开始并重复计算其父节点，直到到达根。 在每个步骤中，确定当前深度 d，在该级别应用 Shift1 和 Shift2 的逆变换，并计算原始未移位树中的正确父代。 
6. 收集在向上遍历过程中所有访问过的节点，并以相反的顺序输出它们，以产生 root 到 X 的路径。 

正确性取决于这样一个事实：在每个级别，父代选择中唯一的模糊性来自该级别的循环排列。 一旦我们使用存储的移位纠正这些排列，标准楼层除以 2 就会产生真正的父代。 

### 为什么它有效

 在每个深度，节点形成由重复的子树和标签移位引起的概念性循环排序。 这两种操作都保留了这样一个事实：每个级别都是原始级别的排列。 该算法隐式地维护精确的累积排列，而不是显式地存储它。 由于二元堆中的父关系仅取决于级别内的相对位置，因此撤消排列会恢复规范结构。 因此，每向上一步都会重建唯一的正确祖先链。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXL = 61

shift1 = [0] * MAXL
shift2 = [0] * MAXL

def get_depth(x):
    return x.bit_length() - 1

def parent(x, d):
    return x // 2

def solve():
    q = int(input())
    res = []

    for _ in range(q):
        tmp = input().split()
        t = int(tmp[0])

        if t == 1 or t == 2:
            x = int(tmp[1])
            k = int(tmp[2])

            d = get_depth(x)
            k %= (1 << d)

            if t == 1:
                shift1[d] = (shift1[d] + k) % (1 << d)
            else:
                shift2[d] = (shift2[d] + k) % (1 << d)

        else:
            x = int(tmp[1])
            path = []

            cur = x
            d = get_depth(cur)

            while cur:
                path.append(cur)
                if cur == 1:
                    break
                d = get_depth(cur)

                # undo both shifts at level d
                mod = (1 << d)
                cur = ((cur - shift1[d] - shift2[d]) % mod) // 2

            res.append(" ".join(map(str, path)))

    print("\n".join(res))

if __name__ == "__main__":
    solve()
```该实现维护两个按深度索引的全局移位数组。 每次更新都会在适当的级别应用模块化增量，确保所有转换都是聚合的而不是模拟的。 

在查询处理期间，向上遍历在应用标准父操作之前通过减去累积移位来重复纠正当前节点。 减法步骤至关重要，因为它在向上移动之前恢复节点在其级别中的规范位置。 

一个常见的错误是除以 2 后应用移位。这破坏了级别索引和堆结构之间的对应关系。 更正必须在移至父级别之前进行。

 ## 边缘情况

 一种重要的边缘情况是 X 非常小时，尤其是 X = 1。在这种情况下，深度为零，并且任何有关级别大小的模算术都必须避免使用零大小的掩码。 由于 (1 << 0) = 1，该算法自然会避免在深度 0 处应用移位，从而使所有移位都为零并防止无效操作。 

当使用较大的负 K 值时，会出现另一种边缘情况。 由于移位是累加模级大小，因此负更新必须正确标准化。 如果没有这个，重复的减法可能会漂移到有效范围之外并产生不正确的父重建。 实现中的模运算确保正旋转和负旋转的一致性。 

最后一个微妙的情况是在同一深度重复更新。 由于类型 1 和类型 2 都是独立积累的，因此重要的是不要过早地合并它们。 将它们分开可确保结构变化不会干扰标签排列，从而在任意交错下保留正确的祖先重建。
