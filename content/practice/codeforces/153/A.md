 ## 解决方案
 ## 问题理解

 我们被要求计算两个整数的和，但重点是仔细的输出格式。 具体来说，输入由两个数字组成，每个数字都在自己的行上，我们需要打印它们的总和，不带任何前导零。 这意味着即使总和是，例如，`00015`，我们应该输出`15`。 

约束很简单：两个整数都在 1 到 100,000 之间。 这些界限足够小，我们不需要担心 Python 中的整数溢出，并且总和将始终小于或等于 200,000。 输入大小很小，因此任何合理的算法都将在微秒内运行； 挑战在于正确性，而不是效率。 

不明显的边缘情况是由于将输入误译为字符串而引起的。 例如，如果一个数字是`"00012"`（从技术上讲，这超出了输入约束，因为 A 和 B 是正整数，但可能出现在问题的变体中），不小心的字符串连接或输出可能会产生`"00015"`而不是`"15"`。 另一种情况是当总和本身恰好是`100000`或某个边界值，它再次测试输出是否为数字并去除了前导零。 

## 方法

 简单的方法将数字视为字符串，将它们转换为整数，将它们相加，然后打印结果。 这是可行的，因为 Python 可以正确处理任意大值的整数算术。 不需要手动实现逐位加法，因为输入范围很小，并且 Python 整数会自动管理结转。 在强力场景中，人们可以尝试从最低有效位到最高有效位迭代每个数字并手动求和，但这会不必要地冗长且容易出错。 

关键的观察结果是 Python 的内置`int`type 已经处理了从字符串中解析数字并在通过转换回字符串时删除前导零`print`。 因此，最佳方法是简单地读取每个数字，将其转换为整数，求和并打印结果。 不需要数组、循环或额外的检查。 在没有大整数支持的假设语言中，暴力方法只会“太慢”，但在这里它实际上是最佳的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 手动逐位加法 | O(log(最大(A,B))) | O(log(最大(A,B))) | 不必要的、冗长的 |
 | Python 内置算术 | O(1) | O(1) | O(1) | O(1) | 已接受，简单正确|

 ## 算法演练

 1. 读取第一行输入并将其转换为整数。 这确保了输入中的任何前导零（如果存在）都会被自动忽略。 
2. 读取第二行输入，并以同样的理由将其转换为整数。 
3. 计算两个整数之和。 
4. 直接打印总和。 这`print`函数将整数转换为字符串，默认情况下不包含前导零。 

为什么它有效：这里的不变性是在每一步我们都对真实的整数值进行操作。 通过立即从字符串转换为整数，我们消除了前导零的任何歧义。 两个正整数之和总是产生一个正整数，并且在Python中打印一个整数可以保证没有前导零，这完全符合问题要求。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

A = int(input())
B = int(input())
print(A + B)
```前两行读取输入并将其转换为整数。 此转换会自动处理去除任何意外的前导零。 The last line computes the sum and prints it. 没有循环或条件，因为问题不需要它们。 由于输入大小非常小，因此该代码在时间和内存限制内运行良好。

 ## 边缘情况

 对于带有意外前导零的输入，例如`"00012"`和`"00003"`，该算法立即将两者转换为整数。 Python解释`"00012"`作为 12 和`"00003"`为 3。总和计算为 15，打印时不带任何前导零。 即使输入格式非常规，内部转换也能保证正确性。 边界值 1 和 100,000 确认不会发生整数溢出或格式错误。
