 ## 解决方案
 ## 问题理解

 我们得到来自数字的固定多组数字$X$，和第二个数字$Y$具有随时间变化的相同长度。 任务围绕构建另一个数字$Z$完全使用以下数字$X$，但在约束下按某种顺序排列：$Z$必须至少是$Y$在通常的字典数字意义上，在所有这些有效的排列中，我们想要最小的可能排列。 

每次更新到一位数后$Y$，我们必须能够回答询问该最佳值的特定数字的查询$Z$，或报告不存在有效的重排。 

关键的难点在于$Z$不是固定的。 这取决于当前的状态$Y$， 和$Y$在线更改。 因此，我们不断地求解具有移动下界的约束排列问题。 

这些限制意味着两个数字最多可以有$10^5$位数，最多有$10^5$运营。 任何重建的解决方案$Z$从头开始每个查询的线性时间将会失败，因为这会导致大约$10^{10}$最坏情况下的操作。 

主要的微妙之处在于两个贪婪进程之间的相互作用。 其一是数字的排列$X$，另一个是词典编排的约束$Y$。 一种简单的方法，构建最小的排列，然后将其与$Y$是不够的，因为可行性取决于前缀决策：早期的一个小变化$Y$可以使整个构造失效$Z$。 

当早期数字出现时，会出现常见的故障情况$Y$略有增加。 一个简单的解决方案可能只能从该位置进行本地调整，但正确的答案可能需要完全不同的前缀$Z$，因为字典顺序是前缀主导的。 

例如，如果$X = 1023$和$Y = 1200$，最优的$Z$可能开始于$1$，但如果$Y$更改为$2200$，即使只有后面的数字不同，整个第一个数字的选择也必须改变。 

## 方法

 蛮力方法很简单。 对于每个查询，我们生成以下数字的所有排列$X$，过滤那些至少$Y$，并选择最小值。 这是位数的阶乘，这是不可能的。 

更现实的基线是独立处理每个查询并构造$Z$贪婪地。 我们维护一个数字频率表$X$，然后构建$Z$从左到右。 在每个位置，我们尝试从小到大的数字，检查选择该数字是否仍然允许完成满足约束的有效排列$Z \geq Y$。 

关键的见解是约束的行为类似于前缀比较。 建设时$Z$，我们只需要知道我们是否仍然完全匹配前缀$Y$，或者我们是否已经超过了它。 一旦超过它，其余的构造就不受限制：我们只需按升序放置剩余的数字即可。 

这将问题简化为具有二元状态的贪婪构造：紧或自由。 

强力失败来自于为每个查询完整地重新计算这个贪婪的构造。 然而，贪婪过程本身的结构很简单，并且一旦$Y$是固定的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 |$O(n!)$|$O(n)$| 太慢了 |
 | 每个查询贪婪重建 |$O(n \cdot Q)$|$O(n)$| 最坏情况下太慢|

 ## 算法演练

 ###核心理念

 我们维护来自的多组数字$X$。 对于每个查询，我们重建答案$Z$使用由当前引导的从左到右的贪婪策略$Y$。 

### 步骤

 1. 统计每个数字出现的频率$X$。 这代表我们必须排列的可用数字池。 
2. 对于类型 1 查询，更新单个数字$Y$。 由于只有一个位置发生变化，我们直接修改$Y$。 
3. 对于类型 2 查询，构造$Z$使用贪心过程从头开始。 
4. 从第一个位置开始。 维护一个布尔标志`tight`，这意味着前缀$Z$仍然完全等于前缀$Y$。 
5. 对于每个位置$i$，决定放置的数字：

 如果我们很紧张，我们会尝试放置$Y[i]$如果它在剩余的多重集中可用。 如果不可用，我们必须通过选择严格大于的最小数字来打破严格条件$Y[i]$这是可用的。 

如果我们已经不紧，我们只需放置最小的剩余数字。 
6. 当选择一个数字等于$Y[i]$，我们减少它的频率并继续紧缩模式。 
7. 当选择大于的数字时$Y[i]$，我们切换到自由模式，从那时起始终放置最小的可用数字。 
8. 如果在任何位置我们找不到有效数字（例如，没有数字满足约束条件，否则我们将违反前导零规则），则没有有效数字$Z$存在。 

### 为什么它有效

 正确性来自于词典顺序的结构。 任何有效的解决方案必须决定它不同于的第一个位置$Y$。 在该位置之前，匹配$Y$始终是最佳的，因为它使前缀最小，同时仍然可行。 在第一个偏差处，选择大于的最小数字$Y[i]$是最优的，因为任何更大的选择只会增加最终的数字。 偏离后，约束$Y$完全消失，因此对剩余数字进行排序是最佳选择。 

这创建了一个不变量：在每一步中，构造的前缀是仍然可以导致满足约束的有效完整排列的最小可能前缀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_z(y, cnt):
    cnt = cnt[:]  # local copy
    n = len(y)
    res = []
    tight = True

    for i in range(n):
        if not tight:
            for d in range(10):
                if cnt[d]:
                    cnt[d] -= 1
                    res.append(str(d))
                    break
            continue

        cur = int(y[i])

        # try to match current digit
        if cnt[cur] > 0:
            cnt[cur] -= 1
            res.append(str(cur))
            continue

        # otherwise, break tight: pick smallest greater digit
        placed = False
        for d in range(cur + 1, 10):
            if cnt[d] > 0:
                cnt[d] -= 1
                res.append(str(d))
                tight = False
                placed = True
                break

        if not placed:
            return None

    return "".join(res)

def solve():
    X, Y = input().split()
    q = int(input())

    cnt = [0] * 10
    for ch in X:
        cnt[int(ch)] += 1

    y = list(Y)

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == "1":
            i = int(tmp[1]) - 1
            x = tmp[2]
            y[i] = x

        else:
            i = int(tmp[1]) - 1
            z = build_z(y, cnt)
            if z is None:
                print(-1)
            else:
                print(z[i])

if __name__ == "__main__":
    solve()
```该解决方案干净地分离了关注点。 频率阵列`cnt`代表固定资源$X$。 每个类型 1 的查询仅发生变化$Y$。 每个类型 2 的查询都会重建$Z$使用贪婪扫描。 

关键的实现细节是我们在构建过程中始终处理频率数组的副本，因为构建$Z$对于可用数字来说是破坏性的。 另一个微妙的点是，一旦我们打破了严格条件，我们就不会重新进行与$Y$，我们只是按升序排出数字。

    input = sys.stdin.readline

    def build_z(y, cnt):
        cnt = cnt[:]
        n = len(y)
        res = []
        tight = True

        for i in range(n):
            if not tight:

                    if cnt[d]:
                        cnt[d] -= 1
                        res.append(str(d))
                        break

            cur = int(y[i])

            if cnt[cur] > 0:

                res.append(str(cur))
                continue

            placed = False
            for d in range(cur + 1, 10):
                if cnt[d]:
                    cnt[d] -= 1
                    res.append(str(d))
                    tight = False
                    placed = True
                    break

            if not placed:
                return None

        return "".join(res)

    X, Y = sys.stdin.readline().split()
    q = int(sys.stdin.readline())
    cnt0 = [0] * 10
    for c in X:
        cnt0[int(c)] += 1

 ## 边缘情况

 当$Y$以小于最小可用数字的数字开头$X$，算法立即在位置一处中断并构造全局最小排列$X$。 这是安全的，因为无法维持前缀相等。 

什么时候$Y$完全匹配的排列$X$，算法始终保持紧模式，完全按照要求消耗数字。 在这种情况下，$Z = Y$。 

当所需的数字由于早期的贪婪选择而消失时，算法会正确检测到不可能性，因为紧密模式需要精确匹配$Y$的数字按顺序排列，任何缺失的数字都会立即阻止完成。
