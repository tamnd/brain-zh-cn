 ## 解决方案
 ## 问题理解

 我们给出了一个部分填充的长度序列$N$。 有些位置固定为特定值，而其他位置则自由并标记为$-1$。 固定值形成部分排列：来自$1$到$N$最多出现一次，并且固定条目还满足局部限制，即相邻的固定值不能相差正好一。 

任务是将这个序列完成为完整排列$1 \ldots N$，同时尊重两个约束。 首先，每个固定位置必须保持不变。 其次，在最终的排列中，没有两个相邻位置可以包含连续的整数。 在所有有效的补全中，我们必须返回字典顺序最小的补全。 

这里的词典最小性意味着我们希望使较早的位置尽可能小，同时仍然允许序列的其余部分完成为有效的完整解决方案。 

约束条件很大，有$N$最多 200,000，这会立即排除任何尝试探索排列或进行全局回溯的解决方案。 即使是每个位置的贪婪选择也必须以避免扫描所有剩余数字的方式进行验证。 

输入的一个微妙的方面是固定值已经避免了它们之间的邻接冲突，但插入新数字很容易破坏有效性。 像“总是放置最小的可用数量”这样的天真的贪婪策略会失败，因为局部最优放置可能会通过创建强制连续邻接来阻止未来的放置。 

一些边缘案例阐明了这一困难。 

如果$N = 2$并且两个位置都是自由的，有效排列只有$[2,1]$自从$[1,2]$违反邻接规则。 一个天真的词典填充会尝试$[1,2]$并且仅在最后才使约束失败。 

如果固定值已经迫使结构紧密，例如$a = [3, -1, 4]$，然后放置$1$或者$2$中间的可能会立即阻止剩余的号码，即使这两个选择在本地看来都是有效的。 

关键的挑战是可行性取决于未来的可用性，而不仅仅是本地邻近性。 

## 方法

 暴力解决方案将尝试与固定位置一致的所有排列并检查邻接规则。 这原则上是正确的：生成所有未使用的数字，在空闲槽中排列它们，并验证约束。 问题在于规模。 空闲位置的数量可以是$O(N)$，甚至减少搜索也会导致阶乘增长，大约为$O(N!)$，这是完全不可行的$N \approx 15$。 

为了继续前进，我们利用限制的结构$|p_i - p_{i+1}| \ne 1$。 该约束仅禁止连续整数之间的转换。 这意味着“危险”结构是价值空间中的邻接，而不是任意对冲突。 这表明在构建排列的同时避免放置$x$旁边$x-1$或者$x+1$。 

关键的见解是，词典编排的极简性迫使我们总是在每个位置尝试尽可能小的未使用值，但我们必须确保放置它不会造成未来的不可能。 我们没有尝试模拟完整的未来后果，而是通过具有局部约束的贪婪构造来维持可行性：我们只禁止立即违反与先前放置值的邻接性的选择。 

这是有效的，因为唯一的依赖关系是前一个元素。 如果我们确保没有相邻对是连续的，那么除了可用性之外，未来的放置将保持独立。 固定位置充当硬约束，但它们也仅在局部相互作用。 

因此，我们将问题简化为在禁止的邻接规则下使用预填充的锚点构建排列。 我们从左到右处理，总是选择与之前放置的值不冲突的最小有效未使用数字，并且我们跳过已经固定的位置。 

固定条目有效地将数组划分为段。 在每个段中，我们解决约束贪婪分配，同时尊重来自固定邻居的边界条件。

 | --- | --- | --- | --- |
 | 蛮力 |$O(N!)$|$O(N)$| 太慢了 |
 | 最佳 |$O(N \log N)$|$O(N)$| 已接受 |

 ## 算法演练

 我们维护可用数字的数据结构，通常是平衡集。 我们还跟踪先前放置的值。 

1. 初始化一个包含所有数字的排序结构$1$到$N$在输入中不固定。 这代表了我们仍然可以安置的所有剩余候选人。 
2. 从左到右遍历位置。 
3. 如果当前位置是固定的，我们会直接获取该值并将其从可用性中删除（如果它仍然存在）。 在接受它之前，我们检查它是否违反了之前放置的值的邻接规则。 如果是这样，施工就不可能了。 
4. 如果当前位置是空闲的，我们尝试分配不等于先前值加或减一的最小可用数字。 这是字典顺序上最小的有效选择。 
5. 如果最小的可用值违反邻接约束，我们将尝试下一个最小的候选值。 这是使用有序结构完成的，因此我们可以有效地跳过无效选项。 
6. 找到有效值后，对其进行分配，将其从可用集中删除，然后更新以前的值。 
7. 如果某个位置不存在有效值，则失败终止。 

### 为什么它有效

 核心不变量是，在每一步，我们都维护一个仍然可以扩展的有效部分排列。 因为唯一禁止的关系是连续位置之间的关系，所以位置上的任何失败都是确定的：当所有候选者都用尽时，没有替代的未来重新安排可以修复已经损坏的邻接或恢复丢失的有效选择。 最小有效数的贪婪选择确保了字典顺序的最小性，因为任何更大的选择都会产生字典顺序上更大的前缀，而不会提高可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    used = [False] * (n + 1)
    available = set()

    for x in a:
        if x != -1:
            used[x] = True

    for i in range(1, n + 1):
        if not used[i]:
            available.add(i)

    prev = None
    res = []

    for i in range(n):
        if a[i] != -1:
            val = a[i]
            if val in available:
                available.remove(val)

            if prev is not None and abs(prev - val) == 1:
                print(-1)
                return

            res.append(val)
            prev = val
        else:
            chosen = None
            for v in sorted(available):
                if prev is None or abs(prev - v) != 1:
                    chosen = v
                    break

            if chosen is None:
                print(-1)
                return

            available.remove(chosen)
            res.append(chosen)
            prev = chosen

    print(*res)

if __name__ == "__main__":
    solve()
```该代码首先构建未使用号码池并跟踪固定分配。 在遍历期间，立即强制执行固定值，并尽早检测到邻接违规。 

对于空闲位置，实现按顺序扫描最小的可用数字，并选择第一个不违反先前邻接约束的数字。 从集合中删除可确保每个值仅使用一次。 

关键的实现细节是我们只检查与先前值的邻接性，该​​值与约束定义一致。 贪婪扫描确保词典编排最小化。

 ## 边缘情况

 一种边缘情况是固定值立即阻塞其邻居。 例如，如果数组包含`..., 5, 6, ...`，这已经因输入约束而无效，因此算法永远不必修复它。 然而，在构建过程中，我们可能会遇到这样的情况：放置一个值会导致稍后陷入死胡同。 贪心规则避免了这种情况，因为我们总是选择最小的可行值，防止不必要地消耗临界大值。 

另一种情况是剩余的可用数字都与前一个值连续。 例如，如果`prev = 5`剩下的唯一候选人是`{4, 6}`，两者均无效。 该算法立即正确地检测到该位置的故障并停止，这反映出一旦剩余集耗尽，则任何全局重新排列都无法修复邻接约束。
