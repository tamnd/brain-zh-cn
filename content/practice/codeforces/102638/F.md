 ## 解决方案
 ## 问题理解

 我们有两组大小相等的字符串。 第一组包含问题，第二组包含准备好的答案。 我们必须为每个问题指定一个答案，并且为每个答案指定一个问题。 

配对两个字符串的分数由它们的韵律长度决定。 在比较两个字符串之前，除了小写英文字母之外的所有字符都会被删除。 分数是两个结果字符串共享的最长后缀的长度。 目标是找到总得分最高的完整配对。 

重要的观察来自于乐谱的结构。 如果我们反转每个处理过的字符串，则公共后缀将成为公共前缀。 经过这种转换后，问题就变成了找到最大权重完美匹配，其中两个字符串的权重是它们最长公共前缀的长度。 

字符串的数量最多为 800 个，所有字符串的总长度最多为 200000。诸如匈牙利匹配之类的通用分配算法过于昂贵，因为它需要大约 O(n^3) 次运算。 当 n = 800 时，这已经是数亿次操作，单独处理字符串比较会使情况变得更糟。 字符串总长度表明预期的解决方案必须集中处理字符而不是比较每一对字符。 

有几个案例很容易被忽视。 如果两个字符串在删除符号后变空，则它们的韵长为零。 例如，问题`!?`和答案`)`产生分数 0。忘记过滤步骤的解决方案可能会错误地将符号视为字符。 

另一种情况是一个字符串是另一个字符串的后缀。 例如，清洁后，`abc`和`xabc`韵律长度为 3，而不是 1。仅比较最后一个字符直到较短字符串结尾的粗心实现仍然可以工作，但仅存储完整后缀而不是反转字符串的所有前缀的解决方案在这里可能会失败。 

第三个重要的例子是重复的结局。 假设两个问题和两个答案都以`ing`。 一个问题的最佳答案不一定是找到的第一个匹配答案。 该算法必须保留每组相等后缀内的所有可用匹配项。 

## 方法

 蛮力方法是计算每个问答对的韵律值，然后解决由此产生的加权二分匹配问题。 一对的权重计算可以在 O(L) 中完成，其中 L 是字符串的长度。 匹配本身可以用匈牙利算法在 O(n^3) 内解决。 尽管这在数学上是正确的，但当 n = 800 时，仅匹配步骤就达到了约 5.12 亿次操作，在此设置中这太慢了。 

关键属性是权重不是任意的。 它们来自颠倒字符串后的 trie 中的公共前缀。 在 trie 中，每个节点代表一组共享某个前缀的字符串。 如果两个字符串经过同一节点的不同子节点，则它们的最长公共前缀恰好在该节点处结束。 这意味着一旦来自不同分支的字符串配对，它们的贡献就已经是固定的。 

最优策略是在 trie 内部递归地解决问题。 首先，我们在每个子子树内创建最好的可能对。 之后，不同子子树中剩余的每个未匹配的问题和答案都可以在当前节点处配对，因为它们都准确地获得了当前深度。 剩余的不匹配字符串被传递给父级，在那里它们可以获得更短的公共前缀。 

蛮力之所以有效，是因为它考虑了每一个可能的分配，但它忽略了许多边具有相同的值。 特里结构压缩了这些相同的关系，让我们立即决定整个组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3 + n^2L) | O(n^3 + n^2L) | O(n^2) | O(n^2) | 太慢了 |
 | 最佳| O(S)| O(S)| 已接受 |

 这里S是所有处理过的字符串的总长度。 

## 算法演练

 1. 从每个字符串中删除所有非小写字符并将剩余字符反转。 将每个问题和答案插入一个共享特里树中。 插入时，存储字符串是属于问题方还是答案方。 

反转是将后缀比较变成前缀比较的转换。 这样，trie 就可以代表所有可能的常见韵律。 
2. 从根开始运行深度优先搜索。 对于每个节点，首先递归地求解其所有子节点。 

子子树已经包含公共前缀长于当前深度的所有可能对。 在考虑仅共享当前前缀的对之前，必须修复这些匹配。 
3.收集孩子返回的不匹配的问题和答案。 当一个孩子提出的不匹配的问题与另一个孩子提出的不匹配的答案同时存在时，将两者配对。 

这些对无法获得当前节点之外的任何其他字符，因为它们在当前节点的正下方分歧。 在这里将它们配对给出了由该节点深度表示的精确分数。 
4. 处理完一个节点后，最多向上返回一侧剩余的不匹配字符串。 由于所有子树已经尽可能地相互匹配，因此剩余的字符串只能与该子树之外的字符串匹配。 
5. 记录每个创建的对，并在每次形成对时将当前深度添加到答案中。 

### 为什么它有效

 不变的是，在处理 trie 节点之后，完全包含在该节点的子树内的每个可能的对都已经被优化。 唯一不匹配的字符串是那些无法在子树内配对而不失去在特里树中更高层更好匹配的可能性的字符串。

每当两个字符串来自节点的不同子节点时，它们的最长公共前缀正是当前节点深度。 未来的操作无法增加它们的价值，因此立即匹配它们总是安全的。 每当两个字符串保留在同一个子字符串中时，递归调用就会处理它们可能更长的公共前缀。 通过从叶到根应用此参数，每对都以其字符串可用的最大贡献来创建。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("children", "q", "a", "depth")
    def __init__(self, depth):
        self.children = {}
        self.q = []
        self.a = []
        self.depth = depth

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)
    questions = [input().rstrip("\n") for _ in range(n)]
    answers = [input().rstrip("\n") for _ in range(n)]

    root = Node(0)

    def add(s, is_question, idx):
        cur = root
        clean = ''.join(c for c in s if 'a' <= c <= 'z')[::-1]
        for c in clean:
            if c not in cur.children:
                cur.children[c] = Node(cur.depth + 1)
            cur = cur.children[c]
        if is_question:
            cur.q.append(idx)
        else:
            cur.a.append(idx)

    for i, s in enumerate(questions):
        add(s, True, i)
    for i, s in enumerate(answers):
        add(s, False, i)

    ans = 0
    pairs = [None] * n

    def dfs(v):
        nonlocal ans

        left_q = list(v.q)
        left_a = list(v.a)

        for child in v.children.values():
            q, a = dfs(child)
            left_q.extend(q)
            left_a.extend(a)

        if v.depth:
            while len(left_q) > 0 and len(left_a) > 0:
                q = left_q.pop()
                a = left_a.pop()
                pairs[q] = a
                ans += v.depth

        return left_q, left_a

    dfs(root)

    out = [str(ans)]
    for i in range(n):
        out.append(questions[i])
        out.append(answers[pairs[i]])
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```插入阶段执行一次所需的归一化。 过滤和反转是在插入之前完成的，因为 trie 必须表示原始问题中的精确后缀关系。 

深度优先搜索是算法的核心。 每个节点返回不匹配的索引，而不是尝试构建完整的匹配矩阵。 这使得内存与 trie 节点的数量成正比。 

配对循环仅在双方都有不匹配的字符串时运行。 仅包含问题或仅包含答案的 trie 节点无法创建有效的对，因此这些字符串会向上传递。 深度是在创建对时精确添加的，因为这是节点表示的公共前缀的长度。 

Python 整数不会溢出，因此最大可能分数不需要特殊处理。 该实现还避免了递归深度问题，因为总字符串长度为 200000，并且最深的可能 trie 路径也可以那么长。 在Python中，对于这种情况应该增加递归限制。

 ## 边缘情况

 如果字符串仅包含标点符号，则它会变为空。 例如：```
1
?!
)
```trie 根直接接收两个字符串。 不存在非零深度，因此算法创建分数为 0 的对。 

如果一个结尾包含在另一个结尾内，则 trie 自然会处理边界。 例如：```
2
abc
xabc
abc
yabc
```反转的字符串共享对应于的前三个特里结构级别`abc`。 在最深的可用节点处形成对，给出分数 3 而不是仅比较最终字符。 

如果许多字符串具有相同的韵律，算法不会贪婪地选择单个最喜欢的字符串。 例如，有几个以结尾的字符串`ing`，它们都经过相同的 trie 路径。 递归过程保留所有不匹配的字符串，直到最深的可能节点，在该节点分配最大可用分数。
