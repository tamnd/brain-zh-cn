 ## 解决方案
 ## 问题理解

 架子是一排`n`职位。 一些位置包含动漫光盘，其余位置包含垃圾。 我们被给予`k`光盘的描述，其中每个描述仅告诉我们该光盘的可能位置范围。 任务是准确确定哪些位置包含垃圾。 

位置表示为`0`如果它包含光盘，则在输出中`1`如果其中含有垃圾。 输入保证有关可能范围的信息足以确定盘的一种独特排列。 

的价值`n`可以高一点`100000`，因此反复尝试许多作业的方法是行不通的。 由于限制在一秒左右，我们需要接近`O(n log n)`或者`O(n)`。 对可能的盘放置位置的强力搜索将呈指数级增长，甚至检查许多可能的间隔组合也将远远超出允许的操作次数。 

棘手的部分是每个间隔并不能告诉我们圆盘的确切位置。 粗心的解决方案可能会选择满足间隔的任意位置，但所选择的位置可能不是唯一的排列。 

例如：```
3 1
1 2
```在位置 1 或 2 的某处有一个圆盘。两种排列都是可能的，因此该输入不会出现，因为答案不是唯一的。 

另一个重要的情况是间隔严重重叠时：```
3 2
1 2
2 3
```将第一个间隔分配给位置 1、将第二个间隔分配给位置 2 的贪心方法会产生有效的排列，但将它们分配给位置 2 和 3 也是有效的。 唯一性保证意味着在官方测试中不会发生这种歧义，但它说明了为什么我们需要一种尊重区间分配结构的方法。 

没有光盘的情况也很特殊：```
5 0
```每个位置都一定是垃圾，所以答案是：```
1 1 1 1 1
```仅处理间隔而忘记初始化剩余位置的解决方案将在这里失败。 

## 方法

 一种直接的方法是尝试将每个圆盘放置在其允许的间隔内的某个位置。 由于可能的放置数量可能是巨大的，这成为间隔和位置之间的匹配问题。 对所有选择进行强力搜索将具有指数级的复杂性。 即使是重复扫描所有间隔以查找可用位置的较慢匹配实现也可以达到大约`O(nk)`操作，大约是`10^10`在最坏的情况下。 

有用的观察是所有约束都是一条线上的间隔。 间隔具有排序属性：当我们处理最早结束的间隔时，我们应该给它当前最早可用的位置。 如果我们延迟这个间隔，具有较大右端点的较晚间隔仍然可以使用较晚的位置，但最早结束的间隔的替代方案较少。 

这就把问题变成了一个贪婪的区间匹配过程。 按右端点对所有圆盘间隔进行排序。 保持下一个可用的货架位置。 对于每个间隔，分配位于其中的第一个未使用的位置。 指定的位置正是光盘位置。 输出只是这些位置的补集。 

蛮力之所以有效，是因为每个有效的分配都必须将每个圆盘放置在其间隔内的某个位置，但它会失败，因为它探索了太多可能的选择。 观察到最早结束的间隔是最具限制性的，这让我们可以立即做出每个选择并避免搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 贪心区间分配 | O((n + k) log k) | O((n + k) log k) | O(n + k) | 已接受 |

 ## 算法演练

 1. 读取所有圆盘间隔并按其右端点对它们进行排序。 当两个区间具有相同的右端点时，它们的顺序不会影响正确性。 
2. 保留一个阵列，标记哪些架子位置包含光盘。 最初，每个位置都被认为是空的。 
3. 对排序后的区间进行一一处理。 对于当前间隔`[l, r]`，选择最小的位置，至少`l`并且之前没有使用过。 将该位置标记为包含光盘。 

我们选择尽可能小的位置的原因是，只有当右侧有更多可用位置时，未来的间隔才会变得更容易。 尽早使用较晚的位置可能会阻止具有较小终点的未来间隔。 
4. 处理完所有区间后，扫描货架。 输出`0`对于标记为圆盘的位置和`1`对于所有其他位置。 

为什么它有效：

 贪心选择保留了完成所有剩余任务的可能性。 考虑尚未处理的区间中右端点最小的区间。 如果它接收到的位置晚于必要的位置，则用最早的可用有效位置替换该位置不会损害任何其他间隔，因为每个剩余间隔的结束时间都不早于该间隔。 对每个间隔重复此参数表明贪婪赋值会产生有效的匹配。 由于该问题保证有效排列是唯一的，因此通过该匹配找到的位置必定是实际的盘位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    intervals = []
    for _ in range(k):
        l, r = map(int, input().split())
        intervals.append((r, l))

    intervals.sort()

    disc = [False] * (n + 1)

    parent = list(range(n + 2))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    for r, l in intervals:
        pos = find(l)
        disc[pos] = True
        parent[pos] = pos + 1

    ans = []
    for i in range(1, n + 1):
        ans.append('0' if disc[i] else '1')

    print(' '.join(ans))

if __name__ == "__main__":
    solve()
```间隔存储为`(right, left)`对，因此排序自然会将最早结束位置的间隔放在前面。 这是贪婪论证所要求的顺序。 

这`parent`array 实现了不相交的集合结构。 这里它的目的不是合并任意集合，而是快速跳过已经分配给光盘的位置。 如果位置`x`使用时，我们将其父级设置为`x + 1`，意味着下一次搜索从`x`会直接跳转到下一个空闲位置。 

这`find`函数返回给定索引处或之后的第一个未使用的位置。 路径压缩使得重复搜索的时间几乎恒定。 这避免了扫描已经占用的位置，否则会使许多重叠间隔变慢。 

位置存储自`1`到`n`，而额外的元素`n + 1`充当安全哨兵。 这可以防止使用最后一个位置时出现超出范围的访问。 

## 工作示例

 对于样本：```
5 0
```没有要处理的间隔。 

| 步骤| 间隔 | 选择的位置| 光盘位置 |
 | --- | --- | --- | --- |
 | 初始| 无 | 无 | 空 |

 最终扫描发现没有位置包含光盘，因此每个位置都是垃圾。 

输出：```
1 1 1 1 1
```对于构造的示例：```
5 2
1 1
2 5
```处理过程是：

 | 步骤| 间隔 | 起始位置| 选择的位置| 光盘位置 |
 | --- | --- | --- | --- | --- |
 | 1 | [1, 1] | 1 | 1 | {1} |
 | 2 | [2, 5] | 2 | 2 | {1, 2} |

 第一个区间只有一个可能的位置，因此强制执行贪婪步骤。 第二个间隔接收最早剩余的有效位置。 

最终输出是：```
0 0 1 1 1
```该轨迹表明，该算法通过始终首先消耗最受约束的可用位置来保留唯一的位置。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(k log k + k α(n) + n) | 排序在区间处理中占主导地位，而不相交集合操作几乎是常数时间 |
 | 空间| O(n + k) | 区间列表、标记数组和不相交集合结构使用线性内存 |

 的最大值`n`是关于`100000`，因此这种复杂性很容易满足内存和时间限制。 不相交的集合结构可以防止大范围内的重复扫描。

 ## 边缘情况

 当没有间隔时，算法永远不会进入贪婪赋值循环。 这`disc`array 仍然完全错误，因此最终的转换将每个位置标记为垃圾。 这处理：```
5 0
```正确并避免假设至少存在一张光盘。 

对于单位置间隔：```
1 1
1 1
```不相交集从位置开始`1`可用的。 该间隔请求第一个可用位置`1`，因此算法将其标记为圆盘并将指针移动到哨兵位置`2`。 输出变为：```
0
```对于接触边界的间隔：```
6 3
1 1
2 3
4 6
```分配如下。 第一个区间接收位置`1`。 第二个接收位置`2`，因为它是里面最早的空闲位置`[2,3]`。 第三个获得位置`4`, 里面最早的空闲位置`[4,6]`。 最终的圆盘位置是`{1,2,4}`，给予：```
0 0 1 0 1 1
```这证实了对可用位置的搜索同时考虑了间隔开始和货架结束。
