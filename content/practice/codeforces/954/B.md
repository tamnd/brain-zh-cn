 ## 解决方案
 ## 问题理解

 我们得到了一个要从空字符串开始构造的字符串。 每个动作都会花费一次操作。 基本操作是将单个字符附加到我们已有的字符的末尾。 此外，在整个过程中，我们可以一次性获取当前构建的字符串并将其精确副本附加到自身上。 

任务是使用最少的操作次数生成给定的最终字符串。 

关键的结构是我们正在逐步构建目标字符串的前缀。 有时，我们可能会选择“加倍”当前前缀，但前提是该前缀与目标字符串的下一段匹配，否则复制操作将立即导致无法匹配最终字符串。 

约束 n ≤ 100 意味着我们可以轻松地提供 O(n^3) 或 O(n^2) 解决方案。 任何尝试所有分割点并检查子串相等性的方法都是可行的。 对前缀的贪婪或动态编程方法就足够了； 我们不需要高级的字符串散列或后缀结构，尽管它们也可以工作。 

一个微妙的边缘情况是最佳策略是根本不使用复制操作。 例如，像abcdef这样没有重复结构的字符串需要全部单字符操作。 另一个边缘情况是存在重复结构但过早使用复制操作比延迟它更糟糕。 

例如，考虑 abcabca。 在 abc 之后复制是有益的，因为下一部分以 abc 开始。 但如果我们尝试在 ab 之后进行复制，我们会得到 ababab，它立即偏离了目标。 

另一个边缘情况是像 aaaaaaa 这样的字符串。 最佳策略是构建一个前缀，然后复制一次，然后键入一些额外的字符。 确切的分割点取决于最大化重复前缀对齐，而不仅仅是任何重复。 

## 方法

 暴力破解的想法很简单：模拟逐个字符构建字符串，并可选择在每个可能的时刻应用复制操作。 在每个前缀长度 i 处，我们决定是否附加下一个字符，或者，如果我们尚未使用复制操作，请尝试复制整个前缀并从那里继续。 这形成了一个状态空间，其中每个状态由当前位置以及副本是否已被使用来定义。 

这是有效的，因为它探索了所有有效的构造序列，但它变得昂贵，因为在每个位置我们分支成两个选择，并且还需要模拟复制。 最坏的情况随着 n 呈指数增长，因为在每个位置我们可能会或可能不会使用复制操作，并且简单的模拟会重复地重新计算字符串连接。 

关键的观察是，复制操作仅在当前构建的前缀与目标字符串的下一段完全匹配时才有用。 如果我们位于位置 i 并且当前构建的字符串长度为 i，则使用复制意味着子字符串 s[0:i] 必须等于 s[i:2i]。 因此，唯一有意义的决定是我们选择加倍的分割点 i，加倍后我们仍然可以单独附加一些剩余的字符。 

这将问题简化为选择前缀长度 i ，以便从该前缀开始将字符串尽可能地分成两个相同的两半，然后最小化总操作：构建前缀的 i 操作，加上 1 次复制操作，加上剩余字符。 

我们尝试从 1 到 n 的所有可能的前缀长度 i，计算加倍保持有效的程度，并相应地计算成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 尝试所有分割点 | O(n^2) | O(n^2) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 假设我们从不使用复制操作，计算答案。 这就是 n，因为我们一一输入所有字符。 这是基线。 
2. 对于从 1 到 n 的每个可能的前缀长度 i，考虑我们使用 i 操作构建前 i 个字符的想法。 
3. 对于选定的 i，检查从位置 i 开始的子串是否与前缀 s[0:i] 匹配。 我们尽可能地扩展此匹配，例如直到位置 j，其中 s[i:j] 等于 s[0:j-i]。 这决定了位置 i 的复制操作有多有用。 
4. 如果我们决定在i处使用复制操作，我们需要支付一次额外的复制操作，然后我们仍然需要单独附加任何剩余的不匹配的后缀字符。 如果完全加倍最多可达 2i，则总成本变为 i + 1 + (n - 2i)，否则我们根据比赛延伸的距离进行调整。 
5. 跟踪所有有效 i 的最低成本。 

为什么它有效：任何最佳解决方案最多使用一次复制操作，因此它必须包含通过键入构建的前缀，后跟该前缀的一个重复项，最后可能是一些最终键入的字符。 每个这样的解决方案都是由发生复制的前缀长度唯一确定的。 通过枚举所有可能的前缀长度并测量重复与目标字符串保持一致的程度，我们探索所有有效的最佳结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    ans = n  # type everything

    for i in range(1, n + 1):
        # build prefix of length i
        j = i
        while j < n and s[j] == s[j - i]:
            j += 1

        # cost: i to type prefix + 1 copy + remaining characters
        remaining = n - j
        ans = min(ans, i + 1 + remaining)

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案迭代我们可能应用复制操作的所有可能点。 对于每个这样的点，它贪婪地扩展复制的前缀相对于目标字符串保持有效的范围。 内部 while 循环确保我们只复制结构匹配的内容； 一旦出现不匹配，进一步复制就会破坏正确性，所以我们停止。 

基线答案 n 处理复制永远没有好处的情况。

 ## 边缘情况

 对于像这样的字符串`abcdef`，算法会尝试每个前缀 i，但匹配的扩展 j 永远不会超出 i。 这使得每个候选成本为 i + 1 + (n - i)，始终为 n + 1，因此基线 n 保持最优。 该算法正确地回退到输入所有内容。 

为了`aaaaaaa`，从 i = 1 开始立即允许完全扩展至末尾，因此成本变为 2，这符合一个字符加复制涵盖所有内容的直觉。 

对于混合重复，例如`ababa`，选择 i = 2 会给出部分扩展，但不会完全覆盖，并且必须键入其余后缀。 该算法通过在第一次不匹配时停止扩展来捕获这一点，确保不计算无效的过度复制。
