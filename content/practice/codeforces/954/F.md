[CF 954F - 跑步者的问题](https://codeforces.com/problemset/problem/954/F)

 ## 解决方案
 ## 问题理解

 我们得到一个 3 × m 的网格，其中移动始终是向右一列，也可以最多垂直移动一行。 旅程从第一列的中间行开始，并且必须在最后一列的同一中间行结束。 每一步总是将列索引增加一，因此路径完全由我们在每列占据的行决定。 

细胞的某些部分被阻塞。 每个限制都表明，对于固定行，连续列间隔中的每个单元格都变得不可用。 如果路径在任何列尝试进入被阻止的单元格，则该路径无效。 

任务是计算从第 1 列到第 m 列存在多少个有效行序列，从第 2 行开始和结束，尊重移动约束并避免阻塞单元格，其中 m 可能大到 10^18，因此我们无法逐列模拟。 

关键的约束含义是任何解决方案都必须避免迭代列。 唯一合理的运算是与障碍物数量呈线性关系或与 m 呈对数关系。 由于 n 高达 10^4，我们可以进行 O(n log n) 或 O(n) 预处理，但不能与 m 成正比。 

对所有列进行简单的动态规划是不可能的。 即使存储 10^18 列的 DP 也是没有意义的。 即使我们压缩，过渡也取决于障碍物边界，而不是单个列。 

重叠的障碍物会产生微妙的边缘情况。 多个障碍物可以堆叠在同一行和同一间隔上。 如果没有正确合并，幼稚的实现可能会错误地将部分阻塞的区域视为单独的区域，并允许通过所谓的阻塞单元进行转换。 例如，如果第 2 行有障碍物 [2,3] 和 [3,4]，则正确的阻挡区域是 [2,4]，而不是两个不相交的区域。 合并失败会导致第 3 列的 DP 转换不正确。 

另一种失败模式是忘记运动严格是向前一列。 这使得问题成为对按列索引的分层图进行路径计数的问题，但边永远不会跳过列。 任何尝试跳过阻塞间隔而不进行仔细状态处理的解决方案都会错误计算路径。 

## 方法

 暴力方法会将每一列视为一个状态，并将 dp[i][j] 计算为到达单元格 (i, j) 的方式数。 如果有效，我们会从每个单元格转换为右上、右和右下。 这正确地模拟了该过程，但 m 最大可达 10^18，因此即使迭代列也是不可能的。 操作次数将与 m 成正比，这远远超出了任何可行的限制。 

当我们观察到每列的转换都是相同的时，问题的结构就会发生变化，除非阻塞事件影响一行。 在阻塞单元集发生变化的两个连续列之间，转换规则是恒定的。 这意味着该过程沿柱轴分段恒定。 

我们可以沿着任何障碍物开始或结束的所有点的列压缩网格。 这将无限列范围减少到最多 2n 个临界点。 在这些点之间，过渡是均匀的，因此我们可以对段长度应用矩阵求幂。 

每个列状态都是一个大小为 3 的向量，表示该列每行中的方式数。 从第 j 列到第 j+1 列的过渡是一个 3 x 3 矩阵，由第 j+1 列中的单元格决定。 对于相同阻塞配置的每个段，我们将该矩阵提高为段长度的幂。 

这将问题简化为对事件进行排序、扫描列段、为每个段构建转换矩阵以及对大间隙应用快速矩阵求幂。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 列上的暴力 DP | O(米) | O(1) | O(1) | 太慢了 |
 | 分段压缩+矩阵求幂| O(n log m) | O(n log m) | O(1) | O(1) | 已接受 |

 ## 算法演练

 ### 1. 将障碍物转换为柱事件

 对于每个障碍物，我们标记在第 l 列，一个单元格被阻塞，而在第 r+1 列，它变得不受阻塞。 我们将这些存储为按行分组的事件。 

此转换将间隔约束转变为列上的扫描线结构。 

### 2.对所有事件位置进行排序

 我们收集所有事件列，对它们进行排序，并处理连续事件点之间的片段。 每个段代表被阻止的单元格不发生变化的范围。 

在两个事件点之间，转移矩阵是固定的，因此我们可以安全地统一处理整个区间。 

### 3. 维护活动的阻塞行

 当我们扫描列时，我们会维护 3 行中的哪一行当前被阻止。 在任何段，这都会给出允许状态的布尔掩码。 

该掩码完全确定哪些转换是合法的。 

### 4. 构建当前段的转移矩阵

 我们定义一个 3 × 3 矩阵 T，其中 T[i][j] 为 1，如果我们可以从第 x 列的第 i 行移动到第 x+1 列的第 j 行，前提是第 j 行未被阻塞。 

每行都可以转换到自身或相邻行，尊重边界和阻塞单元格。 

该矩阵对固定段的所有运动规则进行编码。 

### 5. 使用矩阵求幂跨段跳转

 如果线段的长度为 L，我们使用快速求幂来计算 T^L。 然后我们将其与当前状态向量相乘。 

这使我们能够模拟任意大的 m，而无需逐列迭代。 

### 6. 初始化和完成

 因为我们从第 2 行开始，所以我们从 dp = [0, 1, 0] 开始。我们按顺序处理所有段，重复更新 dp。 最终答案是第 m 列的 dp[1]。 

### 为什么它有效

 该算法依赖于每个段内的不变量，转换结构是恒定的并且与列索引无关。 由于运动在相邻列之间是严格局部的，因此一段上的状态演化正是相同线性变换的重复应用。 矩阵求幂保留了所有可能路径的精确计数，因此压缩相同的转换不会丢失或合并不同的路径。 每个有效路径对应于唯一的行转换序列，并且每个这样的序列在矩阵幂中被计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def mat_mul(a, b):
    res = [[0]*3 for _ in range(3)]
    for i in range(3):
        for k in range(3):
            if a[i][k] == 0:
                continue
            for j in range(3):
                res[i][j] = (res[i][j] + a[i][k] * b[k][j]) % MOD
    return res

def mat_pow(mat, exp):
    res = [[1 if i == j else 0 for j in range(3)] for i in range(3)]
    base = mat
    while exp:
        if exp & 1:
            res = mat_mul(res, base)
        base = mat_mul(base, base)
        exp >>= 1
    return res

def apply(mat, vec):
    return [
        (mat[0][0]*vec[0] + mat[0][1]*vec[1] + mat[0][2]*vec[2]) % MOD,
        (mat[1][0]*vec[0] + mat[1][1]*vec[1] + mat[1][2]*vec[2]) % MOD,
        (mat[2][0]*vec[0] + mat[2][1]*vec[1] + mat[2][2]*vec[2]) % MOD,
    ]

def build_matrix(blocked):
    mat = [[0]*3 for _ in range(3)]
    for i in range(3):
        if blocked[i]:
            continue
        for d in [-1, 0, 1]:
            j = i + d
            if 0 <= j < 3 and not blocked[j]:
                mat[i][j] = 1
    return mat

def solve():
    n, m = map(int, input().split())
    events = {}

    for _ in range(n):
        a, l, r = map(int, input().split())
        a -= 1
        events.setdefault(l, []).append((a, 1))
        events.setdefault(r + 1, []).append((a, -1))

    xs = sorted(events.keys())
    blocked = [0, 0, 0]

    dp = [0, 1, 0]

    cur = 1

    def process_segment(length):
        nonlocal dp, blocked
        if length <= 0:
            return
        mat = build_matrix(blocked)
        matL = mat_pow(mat, length)
        dp = apply(matL, dp)

    for x in xs:
        process_segment(x - cur)
        for a, t in events[x]:
            blocked[a] += t
        cur = x

    process_segment(m - cur + 1)

    print(dp[1] % MOD)

if __name__ == "__main__":
    solve()
```该解决方案将每一行编码为索引 0 到 2，并维护一个到达当前列的每一行的方法向量。 关键的实现细节是，转换始终包括停留在同一行并在有效时移动到相邻行。 

事件应用于列边界，以便每个段都有固定的阻塞配置。 段长度计算使用连续事件位置之间的差异，并且最终刷新处理最多 m 的后缀。 

需要矩阵求幂，因为段长度可能大到 10^18。 每个段都是独立处理的，并且状态以乘法方式向前传播。

 ## 边缘情况

 关键的边缘情况是多个障碍物重叠在同一行和同一间隔上。 基于事件的系统可以正确处理此问题，因为增量和减量会累积到计数器中，因此如果单元的计数器非零，则单元被视为阻塞。 这避免了将重叠间隔视为单独的独立块的错误。 

另一个边缘情况是 m 远大于最后一个事件位置。 最后一段必须一直延伸到 m，否则永远不会考虑超出最后一个障碍物的路径。 该算法显式处理后缀段 m - cur + 1，即使不存在其他事件也能确保正确性。 

最后一个微妙的情况是当一行被某个段完全阻塞时。 在这种情况下，转移矩阵只有零行，这意味着 dp 质量无法进入该行。 求幂仍然有效，因为乘以这样的矩阵自然会消除无效路径，而无需特殊的大小写。
