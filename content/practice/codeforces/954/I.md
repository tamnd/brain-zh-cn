 ## 解决方案
 ## 问题理解

 我们有两个字符串，一个是长字符串，一个是模式字符串，它们都位于一个非常小的六号字母表上。 我们将模式滑过长字符串，对于每个位置，我们采用与模式长度相同的子字符串。 对于每一对等长字符串，我们可以重复应用全局重命名操作：选择两个字符并同时将两个字符串中出现的所有第一个字符替换为第二个字符。 每一个这样的操作都需要一个步骤。 每次对齐的目标是计算所需的此类重命名操作的最小数量，以便子字符串变得与模式相同。 

该操作的关键特征是它在两个字符串中都是全局的。 重命名不会作用于各个位置，而是合并两个字符串中出现的所有字母。 这意味着问题不在于直接匹配位置，而在于强制所有对齐位置上的字母之间保持一致。 

这些约束使得对所有子字符串和所有映射进行暴力破解是不可能的。 长字符串最多可达 125000 个字符，对于每个位置，我们需要处理一个与模式长度相同的窗口。 在最坏的情况下，每个窗口从头开始重新计算结构的简单解决方案将导致大约 1010 次操作。 

小字母表是关键的结构约束。 尽管字符串很长，但只有六个字符。 这立即表明描述窗口的任何状态都可以使用这六个字母上的恒定大小结构来表示。 

当字符在窗口内的不同配对中多次出现时，就会出现微妙的边缘情况。 例如，如果在不同的索引处我们强制 a 等于 b 且 b 等于 c，那么即使没有直接的 a 等于 c 约束，传递闭包也会迫使它们进入同一类。 只计算每个位置的直接不匹配的简单方法在这里失败了，因为它忽略了这种合并传递性。 

另一个微妙的问题是，窗口内同一字母对约束的多次出现不应被重复计算。 一旦存在约束，额外的出现不会改变结构，只有边缘的存在或不存在才重要。 

## 方法

 蛮力观点首先考虑单个窗口。 我们观察子字符串和模式之间的所有索引约束。 每个位置都告诉我们两个字母在重命名后最终必须变得相等。 这些约束定义了一个图，其节点是字母，其边连接的字母必须最终相同。 

对于固定窗口，答案就是使所有连接的组件折叠成单个字母所需的最小合并操作数。 由于每次合并都会将不同字母组的数量减少一个，因此成本完全取决于约束图具有多少个连接组件。 

强力解决方案独立地为每个窗口重新计算该图，构建连接并计算组件数量。 这在概念上是有效的，但对于重叠窗口重复相同的工作。 

关键的观察结果是，当我们滑动窗口时，图形变化非常缓慢。 每一步都会删除一个位置约束并添加一个新约束。 由于约束仅取决于字母对，因此最多有 36 个可能的边。 我们不是从头开始重新计算，而是维护窗口中当前活动的边，并每次在恒定大小的图上重建连接。 

由于字母表是固定的且很小，因此重新计算每个窗口的连接性实际上是恒定的时间。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个窗口重建的暴力破解 | O(n·m) | O(1) | O(1) | 太慢了|
 | 边缘计数上的滑动窗口 | O(n·1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将每个字母视为大小为 6 的图中的一个节点。 对于子字符串和模式之间的每个对齐位置，我们在两个相应字符之间创建一条无向边。 除了第一次出现之外，同一对多次出现并不重要。 

我们维护这些边缘的滑动窗口。 

1. 将两个字符串转换为字母表 a 到 f 上的整数数组，以便我们可以有效地索引它们。 
2. 对于初始窗口，迭代模式长度的所有位置，并为相应的字符对递增 6 x 6 计数器。 这表示哪些约束处于活动状态。 
3. 对于每个窗口，在六个节点上构建一个新的并查找结构。 
4. 对于计数器非零的每对字母，合并这两个节点。 这将构造代表强制相等类的连接组件。 
5. 计算六个节点之间存在多少个连通分量。 
6. 窗口的答案是 6 减去组件数量，因为每次合并都会将组件数量减少 1。 
7. 将窗口滑动一个位置：删除输出对的贡献并添加输入对，然后重新计算答案。 

关键的想法是图非常小，因此即使重建连接，每一步也需要持续不断的工作。 

### 为什么它有效

 每个约束强制要求在所有重命名操作之后最终字符串中的两个字母必须相同。 这是传递性的，因此约束形成等价类。 约束图中的每个连接组件必须折叠成一个字母。 当合并两个先前独立的类时，每个合并操作都会将组件数量恰好减少一个。 因此，最小操作数正是将最初的六个单例节点减少为连通组件数所需的合并次数，即 6 减去该值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    S = input().strip()
    T = input().strip()
    n, m = len(S), len(T)

    S = [ord(c) - 97 for c in S]
    T = [ord(c) - 97 for c in T]

    cnt = [[0] * 6 for _ in range(6)]

    def add(i):
        a = S[i]
        b = T[i]
        cnt[a][b] += 1
        cnt[b][a] += 1

    def remove(i):
        a = S[i]
        b = T[i]
        cnt[a][b] -= 1
        cnt[b][a] -= 1

    for i in range(m):
        add(i)

    def get_answer():
        dsu = DSU(6)
        for i in range(6):
            for j in range(i + 1, 6):
                if cnt[i][j] > 0:
                    dsu.union(i, j)

        comps = 0
        for i in range(6):
            if dsu.find(i) == i:
                comps += 1
        return 6 - comps

    res = []
    res.append(str(get_answer()))

    for i in range(m, n):
        remove(i - m)
        add(i)
        res.append(str(get_answer()))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```该解决方案维护一个 6 x 6 矩阵，用于跟踪窗口当前强制执行的字母对。 每个窗口更新只触及两个位置，因此状态更新是恒定时间。 对于每个窗口，我们重建六个节点之间的连接，这也是常数时间。 最终答案直接来自对连接组件的计数。 

一个常见的陷阱是试图将不匹配视为每个位置的独立成本。 这忽略了传递合并：约束在全局范围内累积，真正的成本取决于等价类的结构，而不是局部不匹配。

 ## 边缘情况

 一种边缘情况是所有字符在每个位置都已匹配。 在这种情况下，不会创建任何边，图形仍保留六个独立节点，并且算法会为每个窗口正确返回零，因为连接组件的数量仍为 6。 

当约束形成跨字母的链时，会出现另一种边缘情况，例如单个窗口内 a 等于 b、b 等于 c、c 等于 d。 即使没有直接的 equals d 约束，联合查找也会将它们合并为一个组件，并且成本正确反映了所需的三个合并而不是一个。 

最终的边缘情况是在同一窗口内重复相同的约束。 频率矩阵可以安全地处理这个问题，因为只有边缘的存在才重要。 即使一对出现多次，它也不会改变连接或过度计数操作。
