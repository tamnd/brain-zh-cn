 ## 解决方案

 ## 问题理解

 墙上的每个位置都可以被认为是需要保护强度的部分。 你会得到一个弓箭手的初始排列，每个弓箭手不仅保卫自己的位置，而且在固定半径内帮助附近的位置。 因此，每个弓箭手不是纯粹的本地贡献，而是将其影响力分散到其位置周围的对称区间内。 

对于城墙的每一部分，其防御力是其影响范围内的弓箭手总数。 防御计划的质量取决于最薄弱的防御部分，这意味着我们关心的是最大化所有阵地的最小覆盖范围。 

你可以在任何地方放置额外的弓箭手，并且每个新弓箭手的行为与现有弓箭手完全相同：它对距离 r 内的所有位置都有贡献。 任务是分配这些额外的弓箭手，以便在所有贡献之后，所有墙段中的最小覆盖范围尽可能大。 

关键的难点在于地方布局与广泛影响力的相互作用。 单个添加的弓箭手会影响整个间隔，因此每个决定都会产生重叠的后果。 

约束足够大，任何二次甚至幼稚的贪婪模拟都立即不可行。 由于位置多达 500,000 个并且 k 可能非常大，任何尝试一一模拟布局或从头开始重新计算覆盖范围的方法都会超出时间限制几个数量级。 这迫使我们采用使用单调性和线性时间可行性检查的策略。 

当 r 很大时，就会出现一个微妙的问题。 在这种情况下，每个弓箭手几乎影响整面墙，因此问题退化为平衡全局总和而不是局部调整。 另一个边缘情况是 r = 0，其中每个位置都是独立的，并且解决方案成为纯粹基于局部赤字的直接再分配问题。 

## 方法

 一种直接的方法是计算每个位置的初始覆盖范围，然后尝试模拟每个额外弓箭手的位置。 每个位置都会更改大约 2r + 1 大小的完整间隔，并且天真地更新此值将花费每个弓箭手 O(n)。 当 k 高达 10^18 时，这甚至无法通过计算来概念化。 

即使我们试图变得更聪明并始终将弓箭手放置在当前最小值最小的位置，我们仍然面临相同的结构性问题：单个放置会影响许多位置，而未来的决策取决于未来的重叠效应。 

关键的观察是答案是单调的。 如果我们能够达到 X 的最低防御水平，那么任何小于 X 的值也是可以实现的。 这使我们能够对最终答案进行二分搜索。 

剩下的挑战是检查固定目标 X 是否可以实现。 这就变成了一个资源分配问题：我们从左到右扫描并确保每个位置至少达到X。如果某个位置有缺陷，我们就被迫放置足够的弓箭手来立即修复它，因为未来的放置无法在不影响早期决策的情况下帮助它。 

每个位置都可以建模为在“覆盖数组”中的连续段上添加覆盖范围，这使我们能够使用差异数组来维持效果并在线性时间内处理所有内容。 

这将问题从“全局选择 k 个放置”转变为“通过范围更新贪婪地满足从左到右的约束”，这是高效且确定的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力模拟 | O(k·n) | O(k·n) | O(n) | 太慢了 |
 | 二分查找+贪心可行性| O(n log V) | O(n) | 已接受 |

 ## 算法演练

我们首先使用前缀和计算每个位置的基础覆盖率，因为每个弓箭手都会贡献固定的间隔。 这为我们提供了添加额外弓箭手之前每个部分的起始强度。 

然后我们对答案进行二分查找，记为 X。 

1. 计算初始覆盖数组b[i]，其中b[i]是现有弓箭手覆盖位置i的数量。 这是使用区间 [i - r, i + r] 上的差异数组来完成的。 
2. 定义一个函数 can(X) 来检查我们是否可以使用最多 k 个添加的弓箭手来确保每个位置的覆盖范围至少为 X。 
3. 在 can(X) 内部，维护一个运行数组 add[i]，表示先前放置的弓箭手贡献的额外覆盖范围。 我们从左到右遍历位置。 
4. 在位置 i，将当前覆盖率计算为 b[i] 加上累积的加法。 如果该值已经至少为 X，我们继续。 
5. 如果低于X，我们将被迫立即修复赤字。 令 need = X - current[i]。 我们将需要的弓箭手放置在位置 i + r。 这个选择很重要，因为它尽可能地扩大覆盖范围，确保我们不会浪费未来的灵活性。 
6. 每个这样的放置都会增加区间 [i, i + 2r] 的覆盖范围。 我们使用差异数组应用此方法，因此更新保持 O(1)。 
7. 累计放置弓箭手的总数。 如果超过 k，则目标 X 无法实现。 
8. 如果我们在不超过 k 的情况下完成扫描，则 X 是可行的。 

二分搜索的运行范围是从初始最小可能值到该值加上 k。 

### 为什么它有效

 贪婪的可行性步骤依赖于强制论证。 当我们处于位置 i 时，那里的任何缺陷都必须由影响力覆盖 i 的某个弓箭手来纠正。 在所有可能的放置位置中，选择最正确的有效位置可以最大化未来的覆盖范围，并且不会降低后续位置的可行性。 一旦我们确定了位置 i，我们就永远不需要重新访问它，因为所有未来的操作只会将覆盖范围扩展到右侧，或者不会以有害的方式影响已经处理的索引。 这创建了一个稳定的从左到右不变量：每个处理的位置都保证永久满足目标。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_base(n, r, a):
    diff = [0] * (n + 2)
    for i, val in enumerate(a):
        if val == 0:
            continue
        l = max(0, i - r)
        rr = min(n - 1, i + r)
        diff[l] += val
        diff[rr + 1] -= val

    b = [0] * n
    cur = 0
    for i in range(n):
        cur += diff[i]
        b[i] = cur
    return b

def can(X, n, r, k, b):
    diff = [0] * (n + 3)
    active = 0
    used = 0

    for i in range(n):
        active += diff[i]
        cur = b[i] + active

        if cur < X:
            need = X - cur
            used += need
            if used > k:
                return False

            active += need
            end = i + 2 * r + 1
            if end < n:
                diff[end] -= need

    return True

def solve():
    n, r, k = map(int, input().split())
    a = list(map(int, input().split()))

    b = build_base(n, r, a)

    lo = min(b)
    hi = lo + k

    while lo < hi:
        mid = (lo + hi + 1) // 2
        if can(mid, n, r, k, b):
            lo = mid
        else:
            hi = mid - 1

    print(lo)

if __name__ == "__main__":
    solve()
```基础计算将每个弓箭手在其影响间隔内进行范围更新，从而在线性时间内产生初始覆盖范围。 可行性检查使用第二个差异数组，但这次是在贪婪扫描期间动态添加的弓箭手。 

关键的微妙之处在于位置 i + r 的放置。 这确保了增加的弓箭手覆盖位置 i，同时最大限度地向右延伸，这对于保持未来决策的可行性至关重要。 

二分搜索包装了这种可行性检查，利用了问题的单调结构。

a = [5, 4, 3, 4, 9]
```由于 r = 0，每个弓箭手只影响自己的位置，因此基础覆盖范围与阵列相同。 

我们测试 X = 5 的可行性。

尝试 X = 6 将在位置 2 处立即失败，因为赤字将超过可用 k。 

该轨迹表明，当 r = 0 时，问题退化为独立的每个索引平衡。

 ## 边缘情况

 当 r = 0 时，每个位置的行为都是独立的，因为没有弓箭手影响邻居。 该算法仍然有效，因为每个赤字都在本地解决，并且贪婪过程永远不会将影响扩展到同一指数之外。 例如，在b[i] = 0且目标X = 3的位置i处，我们直接在该位置花费3个单位，而不影响其他位置。 

当r很大，接近n时，每个添加的弓箭手几乎都会影响整个阵列。 在这种情况下，将所有添加物放置在任何单个最佳位置可以有效地均匀地增加全局最小值。 贪婪扫描仍然表现正确，因为每个位置都会同等地影响所有剩余位置，因此早期决策对于以后的索引仍然有效。 

当 k = 0 时，二分搜索立即崩溃到初始覆盖数组的最小值，并且可行性检查不执行更新，正确反映了不可能进行改进。
