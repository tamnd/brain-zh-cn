 ## 解决方案

 ## 问题理解

 我们得到一个代表密码的基本字符串，以及另一个声称是该密码的“哈希”的字符串。 该哈希值不是通常意义上的加密哈希值。 相反，它的构造方法是获取密码的所有字符，以任意顺序排列它们，然后将该排列嵌入到较大字符串中的某个位置，该字符串前后还包含任意额外的小写字母。 

问题是第二根弦是否可以通过这种方式产生。 换句话说，我们正在检查是否可以找到哈希的子字符串，其字符的多重集与密码的多重字符集完全匹配。 该所选子字符串之外的其余散列可以是任何内容。 

每个测试用例都是独立的，因此我们对多对字符串重复此检查。 

约束很小：两个字符串的长度最多为 100，并且最多有 100 个测试用例。 这立即排除了比总共几百万个简单操作更复杂的事情。 即使 O(n³) 方法仍然是安全的，但任何指数或涉及排列的方法都是不必要的。 

一种常见的错误方法是尝试生成密码的所有排列并在哈希中搜索它们。 这会立即失败，因为即使是 10 个字母的密码也有 10 个！ 排列，这已经太大了。 

另一个微妙的错误是只检查密码是否显示为哈希的子序列。 这是不正确的，因为密码字符在重新排列后必须连续出现，而不是分散出现。 随机播放仅影响所选块内的顺序，而不影响整个字符串的位置。 

一个打破天真的逻辑的小例子：

 输入：```
p = "ab"
h = "axb"
```这里，`"ab"`确实作为子序列出现，但其中不存在长度为 2 的连续子串`h`两者都有`'a'`和`'b'`一起。 所以答案实际上是“不”。 

正确的条件取决于滑动窗口内的匹配字符计数。 

## 方法

 蛮力的想法是考虑每个可能的子串`h`，提取其长度等于`len(p)`，并检查子字符串是否具有相同的字符频率`p`。 对于每个子字符串，我们从头开始重新计算计数，每次检查的成本为 O(26) 或 O(n)。 由于有 O(n) 个子串，这会导致 O(n²) 次检查，每次工作时间为 O(n)，在最坏的情况下为 O(n³)。 

当 n ≤ 100 时，这很容易实现，但仍然超出了需要。 

关键的观察是我们只关心是否有任何子串`h`具有完全相同的多组字符`p`。 这是一个经典的固定长度字谜匹配问题。 我们维护一个大小为 |p| 的滑动窗口，而不是重新计算每个子串的频率。 超过`h`，每步更新字符数为 O(1)。 

我们将窗口的频率阵列与`p`。 由于字母表大小是恒定的（26 个小写字母），因此比较的时间复杂度为 O(26)，这实际上是恒定的。 

这将问题简化为线性扫描`h`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解子串+全计数| O(n3) | O(1) | O(1) | 已接受（但速度较慢）|
 | 滑动窗口频率对比| O(26·n) | O(26·n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 计算密码字符串的频率数组`p`。 该数组存储每个字母出现的次数`'a'`到`'z'`出现。 这是我们必须在某些子字符串中完全匹配的模式`h`。 
2.如果`h`短于`p`，我们立即返回“NO”，因为没有子串`h`可以包含所有字符`p`。 
3. 为第一个窗口构建频率数组`h`长度等于`p`。 该窗口代表候选子串。 
4. 将窗口频率与密码频率进行比较。 如果它们匹配，我们立即返回“YES”。 
5. 一次将窗口滑动一个字符`h`。 每一步：

 - 删除传出角色（窗口左侧）的贡献。 
- 添加传入字符（窗口右侧）。 

这使得窗口频率的更新时间复杂度为 O(1)。 
6. 每次更新后，将更新的窗口频率与密码频率进行比较。 如果在任何时候它们匹配，我们返回“YES”。 
7. 如果我们扫描完所有窗口但没有匹配项，则返回“NO”。 

这个过程正确的原因是每个可能的连续段`h`长度`|p|`作为候选者只检查一次，并且检查每个候选者是否是以下排列`p`。 

### 为什么它有效

 关键的不变量是，在滑动窗口的每一步，窗口的频率数组准确地反映了当前子串的字符多重集`h`长度`|p|`。 由于长度-|p|的每一个可能的位置 子字符串被访问一次，我们永远不会错过有效的候选者。 相反，任何匹配的子字符串都必须显示为这些窗口之一，因此如果没有匹配，则不存在有效的构造。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_one(p, h):
    n, m = len(p), len(h)
    if m < n:
        return "NO"
    
    def freq(s):
        f = [0] * 26
        for c in s:
            f[ord(c) - 97] += 1
        return f
    
    fp = freq(p)
    window = freq(h[:n])
    
    if window == fp:
        return "YES"
    
    for i in range(n, m):
        window[ord(h[i]) - 97] += 1
        window[ord(h[i - n]) - 97] -= 1
        if window == fp:
            return "YES"
    
    return "NO"

def main():
    t = int(input())
    out = []
    for _ in range(t):
        p = input().strip()
        h = input().strip()
        out.append(solve_one(p, h))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该解决方案是围绕检查单个测试用例的助手构建的。 频率数组是长度为 26 的简单固定大小列表，这避免了字典的任何开销。 滑动更新是就地完成的，这确保了窗口之间的恒定时间转换。 

一个常见的实现错误是忘记单独处理初始窗口。 另一个是错误地更新频率数组，特别是混淆了传出和传入索引。 由于这两个操作都是对称的递减和递增，因此默默地交换它们会破坏正确性。

 ## 边缘情况

 一个关键的边缘情况是密码包含重复的字符。 在这种情况下，排列不是唯一的，并且基于顺序的简单子串检查会失败。 例如：

 输入：```
p = "aab"
h = "ababa"
```正确答案是 YES 因为子串`"aba"`或者`"baa"`两者都符合所需的频率。 

滑动窗口可以正确处理这个问题，因为它只跟踪计数，而不跟踪顺序。 每个窗口纯粹根据多重集相等性进行比较，因此自然支持重复项。 

另一个边缘情况是当`h`短于`p`。 例如：```
p = "abc"
h = "ab"
```该算法在进行任何处理之前立即拒绝此操作，因为不存在有效窗口。 这避免了不必要的计算并防止越界滑动逻辑。 

最后一个微妙的情况是有效子字符串出现在`h`。 初始化加上完整的滑动循环确保显式检查最后一个窗口，因此不会错过任何边界情况。
