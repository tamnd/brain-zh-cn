 ## 解决方案
 ## 问题理解

 给定两个整数，并且允许我们重复执行操作，其中第 k 次操作的成本恰好为 k。 每个操作都让我们选择两个数字之一并将当前操作索引添加到其中。 我们想知道所需的此类操作的最小数量，以便在所有选定的增量之后，两个数字变得相等。 

思考这个问题的一个有用方法不是从运算的角度，而是从两个数字之间的差异的角度。 设初始差为$d = |a - b|$。 每一次操作都贡献价值$1, 2, 3, \dots, n$，并且每个值都分配给左侧或右侧的数字。 我们有效地对集合进行了划分$\{1, 2, \dots, n\}$分为两组，我们希望它们的总和之差完全匹配$d$。 

约束允许最多$t = 100$测试用例，每个值可以大到$10^9$。 这立即告诉我们，我们无法显式模拟操作或尝试子集。 甚至$O(\sqrt{d})$每个测试用例可能是可以接受的，但任何差异或操作数量的线性才是真正的目标。 

一个微妙的点是奇偶性。 第一个的总和$n$整数是$\frac{n(n+1)}{2}$。 如果我们想把这个和分成有差异的两部分$d$， 然后$\frac{n(n+1)}{2} - d$必须是偶数，否则不存在分区。 如果人们只贪婪地考虑匹配差异，则很容易忽略这一奇偶校验约束。 

边缘情况出现时$a = b$，答案显然为零。 另一种是当最小$n$达到所需的总和太小，但平价迫使我们增加$n$更远。 例如，如果差值为 1，则$n = 1$有效，因为总和为 1。但对于差 2，$n = 2$给出和 3，由于奇偶校验不匹配，因此不能产生差 2； 我们需要去$n = 3$，其中和为 6，差 2 变得可行。 

## 方法

 蛮力方法会模拟一个一个地增加值，并尝试将每个值分配给其中一个$a$或者$b$，探索所有$2^n$每个可能的操作数的分配$n$。 这是正确的，因为它直接对所有可能的增量分布进行建模，但速度太慢。 即使是为了$n = 30$，这变得不可行。 

我们转变视角：我们不跟踪任务，而是只跟踪任务完成后可以产生的差异$n$运营。 后$n$步骤，总相加和固定为$S = \frac{n(n+1)}{2}$。 任何有效的分配都对应于将此总和分成两个子集，例如$S_1$和$S_2$， 在哪里$S_1 - S_2 = d$和$S_1 + S_2 = S$。 解决这些给出$S_1 = \frac{S + d}{2}$。 所以问题就变成了：找到最小的$n$这样$S \ge d$和$S \equiv d \pmod{2}$。 

这将问题转化为单调搜索$n$，因为三角和稳定增长。 我们可以计算出最小值$n$使用简单的循环或二分搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力分配搜索 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 增量搜索 n | 每次测试 O(√d) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将问题简化为绝对差$d = |a - b|$。 

1. 计算$d = |a - b|$。 如果$d = 0$，因为不需要任何操作，所以立即返回0。 这可以尽早消除琐碎的情况并避免不必要的计算。 
2. 开始于$n = 0$和累计总和$S = 0$。 我们在概念上试图找到最小的$n$这样第一个$n$自然数可以组成划分实现差异$d$。 
3. 增加$n$一步步更新$S = S + n$。 每次增量后，检查是否$S \ge d$。 这确保了我们有足够的总质量来表示所需的差异。 
4.一次$S \ge d$，检查是否$(S - d)$是均匀的。 这个条件保证了$S_1 = (S + d)/2$和$S_2 = (S - d)/2$都是整数，意味着存在有效的分区。 
5.第一个$n$满足这两个条件就是答案。 自从$S$呈二次方增长，这个循环足够快。 

### 为什么它有效

 每一步$n$，我们隐式地考虑所有可能的符号分配给集合$\{1, 2, \dots, n\}$。 可到达的差异正是那些与奇偶性匹配的差异$S$并且不要超过它。 因为增加$n$只扩大可达总和的集合，而不使之前的总和无效，第一个有效的总和$n$保证是最小的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b = map(int, input().split())
        d = abs(a - b)

        if d == 0:
            print(0)
            continue

        n = 0
        s = 0

        while True:
            n += 1
            s += n
            if s >= d and (s - d) % 2 == 0:
                print(n)
                break

if __name__ == "__main__":
    solve()
```解决方案的重点是累积三角形数，直到它们能够表示所需的差异。 该循环是安全的，因为总和增长为$O(n^2)$，因此达到任意$d \le 10^9$发生在大约$O(\sqrt{d})$迭代。 

关键的实现细节是一起检查两个条件：至少达到$d$，并满足平价。 缺少任何一个都会导致错误的答案，特别是对于总和已经足够大但奇偶校验不匹配仍然存在的小差异。

def run(inp: str) -> str:

 ## 边缘情况

 当$a = b$，算法在进入循环之前立即返回 0。 用于输入`5 5`，差值为零，因此不进行累加，无需任何迭代即可输出正确。 

当差异非常小时但奇偶校验早期不匹配时，循环将继续经过第一个看似足够的总和。 为了`1 2`,$d = 1$。 第一步给出$S = 1$，它已经满足了这两个条件，所以答案是 1。然而，对于像 2 这样的其他小差异，我们故意跳过奇偶校验不对齐的中间和，以确保正确性。 

对于较大的值，例如`1 1000000000`，循环不断增长，直到三角和达到或超过差值。 每一步仍然是 O(1)，步数保持在 44700 左右，在约束范围内是安全的。
