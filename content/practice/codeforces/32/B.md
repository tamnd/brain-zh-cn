 ## 解决方案
 ## 问题理解

 我们得到一个用 Borze 编码系统编写的字符串。 三进制数的每个数字都由以下三种模式之一表示：

 -`"."`代表`0`-`"-."`代表`1`-`"--"`代表`2`任务是解码整个字符串并打印生成的三进制数。 

关键细节是编码是前缀安全的。 A single dot always stands alone as`0`，而破折号必须始终与下一个字符配对。 这意味着每当我们遇到`'-'`，我们立即知道当前数字使用两个字符。 

输入的长度最多为 200 个字符，这个长度很小。 即使是二次解也能很好地满足时间限制，因为最坏的情况下它也能处理大约 40,000 个字符操作。 尽管如此，编码的结构自然会导致简单的线性扫描，因此没有理由做额外的工作。 

错误的主要来源是解析字符串时不正确的指针移动。 

考虑输入：```
--.
```正确的解码是：```
20
```粗心的实现可能会读取第一个`'-'`独自一人，无法将其与下一个角色结合起来。 编码规则要求每个破折号消耗两个字符。 

在解码两个字符标记后继续遍历字符串时，会发生另一个容易的错误。 

例如：```
-.--
```正确输出：```
12
```如果我们解码`"-."`作为`1`但仅向前移动一个位置而不是两个位置，即第二个字符`'.'`再次处理并产生错误的结果。 

最后的边缘情况是完全由点组成的字符串：```
...
```正确输出：```
000
```前导零必须完全按照解码的方式保留。 将结果转换为整数会错误地将其折叠为单个`0`。 

## 方法

 最直接的暴力破解想法是反复尝试将当前前缀与三个有效的 Borze 符号进行匹配。 在每个位置，我们检查子字符串是否以`"."`,`"-."`， 或者`"--"`，附加相应的数字，然后继续。 

这是可行的，因为编码规则是明确的。 一旦我们检查当前字符以及必要时检查下一个字符，任何有效符号都不会与另一个字符混淆。 

即使在每一步都创建子字符串的情况下实现效率低下，输入也很小，因此解决方案仍然可以顺利通过。 当长度最多为 200 时，重复切割字符串在几万次操作下仍然可以保持良好状态。 

进一步简化问题的观察是，实际上只有两种情况：

 - 如果当前字符是`'.'`，答案数字肯定是`0`。 
- 如果当前字符是`'-'`，我们只需要检查下一个字符：

 -`"-."`方法`1`-`"--"`方法`2`这让我们可以使用索引指针在一次从左到右的扫描中处理字符串。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 已接受 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取 Borze 字符串。 
2. 创建空结果字符串并初始化索引`i = 0`。 
3.同时`i`位于字符串内部：

 1.如果`s[i]`是`'.'`, 附加`'0'`找到答案并行动`i`前进 1。 
2. 否则当前字符为`'-'`，因此该数字必须使用两个字符。 

- 如果`s[i + 1]`是`'.'`, 附加`'1'`。 
- 否则附加`'2'`。 

移动`i`前进2。 
4. 打印构建的答案字符串。 

### 为什么它有效

 编码规则将输入划分为不重叠的有效标记。 

点始终构成标记`"."`，并且破折号总是以任一方式开头`"-."`或者`"--"`。 因此，正确的标记位于位置`i`由当前角色以及可能的下一个角色唯一确定。 

该算法始终准确地消耗属于当前数字的字符，从不跳过字符，并且从不处理一个字符两次。 每一步之后，每个处理的前缀都已被正确解码。 扫描完成后，整个字符串已被解码。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()

ans = []
i = 0

while i < len(s):
    if s[i] == '.':
        ans.append('0')
        i += 1
    else:
        if s[i + 1] == '.':
            ans.append('1')
        else:
            ans.append('2')
        i += 2

print(''.join(ans))
```解决方案保留一个指针`i`表示 Borze 字符串中当前未读的位置。 

当当前字符为`'.'`，映射是立即的。 我们追加`'0'`并向前移动一步，因为该令牌仅使用一个字符。 

当当前字符为`'-'`，我们必须检查下一个字符来区分`"-."`和`"--"`。 两种情况都会消耗两个字符，因此指针前进 2。 

答案存储在列表中，而不是重复连接字符串。 对于这个问题，任何一种方法都可以通过，但是列表积累后面跟着`''.join()`是Python中标准的高效模式。 

边界访问`s[i + 1]`始终是安全的，因为保证输入有效。 孤独的尾随`'-'`永远不可能出现。

import sys
import io

def solve():
    s = input().strip()

    ans = []
    i = 0

            i += 1
        else:

 ## 边缘情况

 考虑输入：```
--.
```算法从索引开始`0`并看到`'-'`。 它检查下一个字符并找到另一个`'-'`，所以它附加`2`并前进2个位置。 现在`i = 2`，其中剩余的字符是`'.'`，生产`0`。 

最终的答案是：```
20
```这证实了两个字符的令牌被一起消耗并且从未被部分处理。 

现在考虑：```
-.--
```在`i = 0`, 子串`"-."`变成`1`，指针直接跳转到`i = 2`。 剩余子串`"--"`变成`2`。 

输出是：```
12
```如果解码后指针仅前进一位`"-."`，第二个字符将被再次解析并破坏结果。 

最后，考虑：```
...
```每个点独立映射到`0`，生产：```
000
```该算法将结果存储为字符串，因此前导零保持不变。 通过整数进行转换会错误地丢失信息。
