 ## 解决方案
 ## 问题理解

 我们给出了一个建模为 n × m 网格的矩形停车场。 有些牢房设有柱子，永久阻碍移动和停车。 剩下的牢房是空的，汽车最终可能会停下来。 

汽车不能在网格中自由移动。 每辆车选择一行或一列入口，然后沿着该线直线向内移动。 汽车继续行驶，直到它到达行或列的远端，或者由于其路径中的下一个单元被柱子或已经停放的汽车阻挡而被迫提前停止。 一旦汽车停下来，它就会永久占据该单元并成为后面汽车的障碍。 

规划者可以为每辆到达的车辆选择应使用哪个入口。 目标是在没有有效移动之前最大限度地增加可以成功停放的车辆数量。 

输入只是描述柱子和空单元的网格，输出是一个数字：在最佳入口选择序列下可以停放的最大汽车数量。 

关键的结构约束是，一旦汽车进入，运动就严格是一维的，因此每个决策仅影响单个行或列线。 这立即表明问题不在于网格中的一般路径查找，而在于沿独立线性段的相互作用。 

网格大小可达 1000 x 1000，因此，任何在最坏情况下尝试通过重复扫描行或列来显式模拟每辆汽车的方法，如果经过仔细优化，仍然可以接受，但任何考虑所有放置对或在每次放置后重新计算可达性的方法都将太慢。 尝试所有可能的汽车放置并反复更新网格的简单模拟会在密集情况下退化为立方体行为。 

当多个行或列具有相似的“立即停止点”时，就会出现贪婪直觉的微妙失败情况。 例如，如果一行在其入口附近有一个空单元格，而另一行有较长的空单元链，则首先选择短的空单元格可能会阻止稍后相交列中的访问模式。 这意味着如果没有对行和列之间的交互进行全局考虑，局部最短或最长启发法是不可靠的。 

## 方法

 直接的暴力解释是模拟停车过程。 在每一步中，我们都会考虑每个可能的入口，模拟汽车沿其行或列移动，并在可能的情况下放置它。 然后，我们递归地继续，直到不再有可能的放置位置，尝试所有可能的入口选择。 

这是正确的，因为它探索了每一种可能的决策顺序。 问题在于，每次放置后，网格都会发生变化，因此必须一次又一次地重新计算同一行或同一列。 每个模拟步骤扫描 O(n + m) 个单元，在最坏的情况下，我们可能会放置 O(nm) 辆汽车，导致总复杂度约为 O(nm(n + m))，这对于 1000 x 1000 个网格来说太慢了。 

关键的观察结果是，最终的配置并不取决于我们模拟汽车的确切顺序，而只取决于在被阻止之前可以从行或列的任一侧到达哪些单元格。 一旦一个单元格被汽车“消耗”，它的行为就像是未来汽车在其行和列中的拦截器，因此该过程相当于重复匹配空闲段的可用端点。 

查看网格的一种更有用的方法是将其分解为由柱子分隔的空单元格的最大连续段。 每个这样的部分在线性运动方面都是独立的。 从左侧或右侧进入一行的汽车本质上声称从该侧开始的一段中的第一个可用单元格，对于列也是如此。

我们的见解是，每个空单元格实际上都是一个候选者，可以从其行中最多两个方向和列中最多两个方向“使用”，但一旦被使用，它就会阻止未来的访问。 这在行段和列段之间创建了双向交互，最佳策略是计算可以在不发生冲突的情况下声明多少个单元格。 

这简化为一个经典的想法：我们贪婪地匹配可用的行可访问单元和列可访问单元，但我们没有显式地构建图，而是利用这样一个事实：每个单元都可以从正好四个方向的“前部”（左、右、上、下）到达，并且每个汽车的放置都会减少本地可用的前部。 

我们通过跟踪每一行和每一列剩余的可用入口点来模拟该过程，并重复将汽车分配到它们可以到达的最早可用的阻塞位置。 由于每次分配仅删除一个单元格并更新两行，因此总工作量与单元格数量保持线性关系。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 所有序列的暴力模拟 | O(nm(n + m)) | O(纳米) | 太慢了|
 | 行/列段贪婪匹配 | O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 1. 我们首先对网格进行预处理，以了解对于每一行和每一列，如果汽车从任一侧进入，它们会停在哪里。 这意味着从左到右、从右到左扫描每一行，同样地扫描每一列，只要遇到柱子就停止。 这一步的原因是每辆车总是停在第一个障碍物处，因此我们只需要每个方向上最近的障碍物结构。 
2. 我们维护一个结构来标记单元格是否仍然可以接收汽车。 最初都是“.” 单元格可用，而“o”单元格则永久阻塞。 这种状态是必要的，因为一旦汽车占据了一个单元格，它就会成为该行和列中未来汽车的阻挡者。 
3.对于每一行，我们模拟从两端向内重复发送汽车的效果。 我们从概念上将每一行视为由支柱分隔的可用位置的双端队列。 每次我们将一辆车分配到一行时，它都会占据一侧最近的可用单元格并将其从进一步的考虑中删除。 同样的想法对称地适用于柱。 
4. 我们重复一个全局过程，只要存在有效端点，我们就会尝试水平或垂直放置汽车。 当放置发生时，我们从其行和列结构中删除该单元格。 这确保了水平和垂直流之间的一致性。 
5. 我们继续这个过程，直到没有行或列可以放置另一辆车，这意味着每个剩余的段要么被阻塞，要么已经耗尽。 
6. 最终答案是在此过程中成功放置的次数。 

这样做的原因是每个有效的放置都是强制的：进入行或列的汽车总是最终位于该方向上第一个可到达的空单元格中。 一旦方向固定，线段内部就没有选择。 唯一的决定是我们首先消耗行端点还是列端点，但是任何尊重可用性约束的排序都会导致相同的最大计数，因为每个单元最多可以消耗一次并且恰好贡献一个容量单位。 

保持的不变性是，在任何时候，每个剩余的空闲单元仍然可以从至少一个方向到达，而无需穿过先前分配的单元或支柱，并且每次分配都精确地删除一个这样的可到达单元，同时正确地更新其在两个方向上的邻居的可达性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [list(input().strip()) for _ in range(n)]

    row_used = [[False] * m for _ in range(n)]
    col_used = [[False] * m for _ in range(n)]

    ans = 0

    changed = True
    while changed:
        changed = False

        for i in range(n):
            j = 0
            while j < m:
                if g[i][j] == 'o' or row_used[i][j]:
                    j += 1
                    continue

                l = j
                while j < m and g[i][j] == '.':
                    j += 1
                r = j - 1

                if l <= r:
                    if not row_used[i][l]:
                        row_used[i][l] = True
                        col_used[i][l] = True
                        ans += 1
                        changed = True

        for j in range(m):
            i = 0
            while i < n:
                if g[i][j] == 'o' or col_used[i][j]:
                    i += 1
                    continue

                l = i
                while i < n and g[i][j] == '.':
                    i += 1
                r = i - 1

                if l <= r:
                    if not col_used[l][j]:
                        col_used[l][j] = True
                        row_used[l][j] = True
                        ans += 1
                        changed = True

    print(ans)

if __name__ == "__main__":
    solve()
```该实现在水平和垂直扫描之间交替。 在每次扫描中，它将连续的空单元分组为由柱子分隔的片段。 只有每个路段的第一个无人认领的单元用于新车，因为它对应于入口处的第一个停车点。 这`row_used`和`col_used`数组确保一旦获取一个单元格，就会一致地将其从两个方向移除。 

一个常见的实现陷阱是忘记在行扫描中删除的单元格必须立即在同一迭代中的列扫描中变得不可用。 如果没有这种同步，同一细胞可能会在不同方向上计数两次。

 ## 边缘情况

 一种边缘情况是一行或一列除了单个单元格之外完全被柱子填充。 在这种情况下，只能使用该孤立的单元，并且无论是通过行扫描还是列扫描发现它，都必须精确计数一次。 该算法处理这个问题是因为一旦一个单元格被标记为在任一方向使用，它就会被排除在另一个方向之外。 

另一种边缘情况是具有交替柱子的网格，形成许多单细胞段。 每个段最多贡献一辆车，段与段之间不发生干扰。 分段逻辑确保每个都独立处理。 

最后一个微妙的情况是，在同一迭代中可以从行和列访问单元格。 如果没有共享标记数组，它可能会被计数两次。 在这里，一旦在任一扫描中进行放置，该单元就会立即从行和列考虑中删除，从而防止重复。
