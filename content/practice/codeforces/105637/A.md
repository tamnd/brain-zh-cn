 ## 解决方案
 ## 问题理解

 我们有一个简单的模型来说明价格如何随时间变化。 有一个代表第一天价格的初始值，然后对于随后的每一天，我们都会得到与前一天相比价格变化的程度。 每次更改都会累积应用，因此第 i 天的值是第 i−1 天的值加上第 i−1 个更改。 

任务是计算应用所有每日更改后的最终值，即最后一天的值。 

虽然这个说法听起来像是一个“时间过程”，但其结构却是纯粹的线性积累。 每次更新都是附加且独立的，因此我们实际上只是在更改数组上重建前缀和。 

输入量较小，最多 1000 天。 这立即告诉我们，即使是简单的 O(n) 扫描也绰绰有余，因为在典型限制下 10^3 次操作可以忽略不计。 任何超出线性时间的解决方案都会产生不必要的开销。 

一些边缘情况值得牢记。 

如果只有一天，则无需应用任何更改，因此答案只是初始值。 总是尝试读取至少一项更改的幼稚实现在这里会失败。 

如果所有变化都是负的，根据问题保证，最终价格仍然可以保持正值，但是中间实现意外地将值限制为零（模拟式思维中的常见错误）会产生不正确的结果。 

如果更改包含零，则数学上不会发生任何特殊情况，但在假设零条目不相关的情况下跳过零条目的实现会破坏正确性。 

## 方法

 暴力解释将日复一日地模拟这个过程。 我们从初始价格开始，迭代每次更改，每次更新当前值。 这已经是 O(n) 时间了，因为每天都会贡献一个恒定时间的更新。 没有隐藏状态，没有分支，也没有组合爆炸。 

试图进一步“优化”会错过结构的要点。 关键的观察结果是，最终值仅取决于所有变化的总和，而不取决于它们的顺序或中间状态。 重复的更新会分解为一个算术表达式：初始值加上所有每日差异的总和。 

因此，最佳方法不是采用不同的算法技术，而是认识到模拟和直接求和在这里是相同的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 逐步模拟| O(n) | O(1) | O(1) | 已接受 |
 | 直接变化总和| O(n) | O(1) | O(1) | 已接受 |

 两者在实践中实际上是相同的实现。 

## 算法演练

 1. 读取天数n。 这决定了将应用多少更新。 
2. 读取初始价格。 这是任何更改之前的起始状态。 
3. 使用该初始价格初始化可变电流。 
4. 对于接下来的 n−1 行中的每一行，读取每日变化并将其添加到当前。 每一次添加都恰好对应于时间向前移动一天。 
5. 处理完所有变更后，输出当前价格作为最终价格。 

关键的决定是我们永远不需要存储完整的值序列。 每个中间价格仅作为临时状态存在，并且由于每个转换都是可加的，因此仅保留当前值可以保留所有必要的信息。 

### 为什么它有效

 该过程定义了 value[i] = value[i−1] + delta[i] 形式的递归。 重复展开此递归式表明 value[n] 等于初始值加上所有增量之和。 由于加法是结合的，所以运算的分组并不重要，并且除了贡献一次值之外，没有任何中间步骤会影响最终结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    cur = int(input())
    
    for _ in range(n - 1):
        cur += int(input())
    
    print(cur)

if __name__ == "__main__":
    solve()
```该代码直接实现了演练中描述的递归。 变量`cur`代表不断变化的价格。 每个输入行都会立即应用，避免不必要的整个数组存储。 

一个常见的实现错误是尝试将所有值存储在列表中并稍后重新计算。 这是不必要的，但在这里仍然安全。 更严重的错误是错误地初始化累加器，例如从零开始而不是从给定的初始价格开始，这会改变整个结果。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个每日更改都会处理一次 |
 | 空间| O(1) | O(1) | 仅维护一个累加器变量 |

 限制最多允许 1000 天，因此单次线性传递完全在限制范围内。 即使界限更大，相同的方法仍然可以有效地扩展，因为它避免了任何嵌套计算。

 ## 边缘情况

 对于单日输入，算法读取初始值并且永远不会进入循环，因此输出正是该值。 不存在未初始化更新的风险，因为累加器是根据输入立即设置的。 

对于纯负数序列，每次减法都直接应用于运行总计。 该算法在任何时候都不假设正性，因此它自然地跟踪减少而不会出现钳位或溢出问题。 

对于零变化，每次迭代执行`cur += 0`，保持状态不变。 由于没有条件过滤掉零值，因此它们被正确地包含在统一累积过程中。
