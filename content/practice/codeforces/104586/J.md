 ## 解决方案
 ## 问题理解

 我们得到一组放置在一条线上的垂直柱，每个柱由 x 轴上的位置和高度定义。 我们可以选择两个不同的帖子，一个作为“掉落”帖子，一个作为“目标”帖子。 旋转落下的柱子，使其顶部接触目标柱的顶部，与地面形成直角三角形。 

从几何角度来看，该三角形的底边是两个选定位置之间的水平距离，垂直分量由目标柱的高度确定，因为目标的顶部定义了三角形的上顶点。 落下的柱子仅充当连接器，必须足够高才能到达该点，但一旦配置有效，它就不会独立地影响三角形的高度。 

目标是选择一对有序的不同索引来最大化该直角三角形的面积。 如果不存在产生正面积的有效配置，我们输出 -1 -1。 

限制允许最多 100,000 个帖子，坐标最多为 10^9。 这立即排除了任何显式考虑所有对的解决方案，因为在最坏的情况下这将需要大约 10^10 次操作。 我们需要更接近 O(n log n) 或 O(n) 的东西。 

此类问题的一个微妙问题是，下落柱的方向仅与可行性有关，与最终面积公式无关。 许多不正确的解决方案会意外地将问题视为对称问题或忽略排序约束，这会在最佳配置取决于首先选择正确的“目标”帖子的情况下导致错误的答案。 

另一种失败模式来自于假设最佳对始终由按 x 坐标排序后的相邻帖子形成。 例如，考虑：

 输入：```
3
0 100
1 1
10 1
```贪婪邻接方法可能会尝试 (0,1) 或 (1,10)，但最佳结构取决于将极端距离与足够的高度约束相结合，而邻接无法捕获这一点。 

最后，另一个陷阱是忽略了给定帖子的最佳合作伙伴取决于过滤后的集合中的全局极值，而不是本地邻居。 

## 方法

 暴力解决方案会尝试每对有序的帖子。 对于每一对，我们计算使用一个作为下落柱、另一个作为支撑所隐含的三角形面积。 这是简单且正确的，因为它直接检查所有配置。 然而，它需要检查 n(n−1) 对，并且每次检查的时间复杂度为 O(1)，导致时间为 O(n^2)，这对于 n = 100,000 来说远远不可行。 

关键的观察结果是，对于固定的“目标”柱，其面积仅取决于其高度以及与最佳可能合作伙伴的距离。 如果我们将目标柱固定为 b，则最佳落下柱 a 始终是最大化 |x_a − x_b| 的柱。 同时仍然满足a足够高到达b的可行性条件。 

这表明我们要扭转观点：我们不是枚举对，而是按照高度递减的顺序处理帖子。 当我们处理一个帖子时，所有之前处理过的帖子的高度至少一样大，因此它们是当前帖子的有效候选者。 在这些候选者中，我们只需要最小和最大 x 坐标即可最大化距离。 

这减少了维护动态点集并快速访问极端 x 值的问题。

 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 排序+极值扫描| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 ### 1. 按高度降序对帖子进行排序

 我们首先对所有帖子进行排序，以便我们始终首先处理较高的帖子。 这确保了当我们考虑帖子时，之前处理的每个帖子至少都一样高。 

这种顺序至关重要，因为它保证了可行性：任何较早的帖子都可以作为当前帖子的下一个帖子。 

### 2. 维护一组动态的 x 坐标

 我们维护一个存储所有先前处理的帖子的 x 坐标的结构。 从这个集合中，我们只需要跟踪最小和最大 x 值。 

这两个极端就足够了，因为它们最大化了到任何新点的水平距离。 

### 3. 将每个帖子作为当前目标处理

 对于按排序顺序的每个帖子 i，我们将其视为潜在目标。 如果我们已经处理了帖子，我们会计算从 i 到当前极值的最佳可能距离：

 我们评估距离 = max(|x_i − min_x|, |x_i − max_x|)。 

然后我们计算候选区域 = h_i × 距离。 

这对应于使用 i 作为支撑柱并将其与最远的有效落下柱配对。 

### 4.更新最佳答案

 我们跟踪迄今为止找到的最大区域并存储相应的有序索引对。 

### 5. 将当前帖子插入结构中

 处理完 i 后，我们将其 x 坐标插入到结构中，以便它可用于将来（较短的）帖子。 

### 为什么它有效

 在任何一步中，所有先前处理的帖子的高度都大于或等于当前的高度，因此它们是有效的掉落帖子。 对于每个目标柱，最佳落下柱必须位于当前 x 范围的两端之一，因为距离在 x 中是线性的并且在极端处最大化。 这确保了我们永远不会错过可以产生更大面积的候选点，因为任何内部点都不能产生比极值更大的水平距离。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = []
    for i in range(n):
        x, h = map(int, input().split())
        pts.append((h, x, i + 1))
    
    pts.sort(reverse=True)

    min_x = None
    max_x = None

    best_area = 0
    best_pair = (-1, -1)

    for h, x, idx in pts:
        if min_x is not None:
            d1 = abs(x - min_x)
            d2 = abs(x - max_x)
            if d1 >= d2:
                area = h * d1
                if area > best_area:
                    best_area = area
                    best_pair = (idx, pts_map_min[min_x])
            else:
                area = h * d2
                if area > best_area:
                    best_area = area
                    best_pair = (idx, pts_map_max[max_x])

        if min_x is None:
            min_x = max_x = x
            pts_map_min = {x: idx}
            pts_map_max = {x: idx}
        else:
            if x < min_x:
                min_x = x
                pts_map_min[x] = idx
            if x > max_x:
                max_x = x
                pts_map_max[x] = idx

    if best_area == 0:
        print(-1, -1)
    else:
        print(*best_pair)

if __name__ == "__main__":
    solve()
```实现直接遵循扫描思想。 该数组按高度排序，以便在与先前看到的点配对时保证可行性。 

我们维护已处理点之间的最小和最大 x，以及用于检索相应索引的映射。 每个新点都会与两个极端进行比较，因为只有这些才能最大化距离。 

一个微妙的实施问题是，两个极端都必须与其原始索引一起跟踪。 如果随着时间的推移多个点共享相同的极值 x，我们必须确保我们仍然引用有效的索引。 这里的字典就是为了这个目的，尽管更简单的实现可以显式存储 min 和 max 的 (x, idx) 对。 

对 best_area == 0 的检查处理不存在有效对的情况，这意味着我们从来没有至少两个兼容点。

 ## 边缘情况

 具有两个点的最小输入总是产生唯一可能的对，算法通过插入第一个点并立即根据它评估第二个点来处理它。 扫描可确保第一个点在需要时准确地成为候选集的一部分。 

当所有点都具有相同的高度时，每个点都变得同样有效作为目标。 该算法简化为选择具有最大水平距离的对，这是使用维护的最小和最大 x 值正确找到的。 

如果点聚集在 x 中，但有一个点距离很远，极限跟踪可确保远点在成为处理集的一部分时始终被选择，从而防止任何局部聚类主导答案。
