 ## 解决方案
 ## 问题理解

 我们收到一条分成单词的短消息，我们想要确定在传输错误后特殊关键字“codecup”是否可能出现在该消息中的某个位置。 

关键细节是误差模型。 每个传输的字在传输过程中最多可能丢失一个字符，但字符永远不会改变，并且字之间不会发生任何其他情况。 因此，每个观察到的单词要么完全是原始单词，要么是原始单词在其中某处删除了单个字符。 不允许替换，也不允许多次删除。 

任务是检查任何观察到的单词是否可以对应于该规则下的预期单词“codecup”。 如果至少有一个单词可能是“codecup”的损坏版本，那么答案是肯定的。 

输入大小很小：最多 100 个字，每个字的长度最多为 25。这消除了繁重预处理或高级数据结构的任何压力。 每个字的直接检查就足够了，因为每次检查仅涉及长度为 7 的固定模式。 

一个微妙的一点是，我们不允许通过改变字符来“修复”一个单词。 我们只从原始“codecup”中删除最多一个字符以获得接收到的单词。 这种不对称性很重要，因为它可以防止将其与一般编辑距离混淆。 

主要的边缘情况是当单词几乎正确但在两个位置不同时。 例如，“codecap”通过替换而不同，这是无效的，而“cdecp”对应于两次删除，也是无效的。 两者都应该正确失败。 

## 方法

 强力解释会尝试将每个消息单词与从“codecup”中删除字符的所有可能方法对齐。 由于“codecup”的长度为 7，因此只有 8 种可能性：不删除任何内容或仅删除 7 个位置之一。 对于每个单词，我们可以生成这 8 个候选词并进行比较。 

这已经在一定范围内发挥作用，但有点间接。 更清晰的观察是我们根本不需要生成修改后的模式。 相反，我们可以使用两个指针针对“codecup”扫描单词，并允许在模式中最多跳过一个字符。 这直接编码了“最多从原始内容中删除一个”约束。 

蛮力方法之所以有效，是因为模式空间很小，但如果泛化，它在概念上就会变得混乱。 两指针公式将所有内容简化为每个单词一次线性扫描，并使正确性更容易推理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 枚举删除 | O(n·7) | O(1) | O(1) | 已接受 |
 | 两指针跳过检查 | O(n·7) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将“codecup”视为长度为 7 的固定参考字符串，并独立测试每个单词。 

1. 对于消息中的每个单词，尝试使用两个指针将其与“codecup”进行匹配，一个用于单词，一个用于模式。 

目标是在推进模式时消耗整个单词，最多允许模式中跳过一个字符。 
2. 初始化两个索引，一个用于单词，一个用于模式，以及一个用于记录我们跳过的模式字符数量的计数器。 

跳过计数器表示损坏之前原始单词中允许的单个删除。 
3. 当两个指针都在边界内时，比较字符。 如果它们匹配，则将两个指针都前移。 

这对应于在传输中幸存下来的字符。 
4. 如果它们不匹配，我们尝试跳过模式中的一个字符，增加跳过计数器并仅前进模式指针。

这模拟了该模式字符可能是在传输之前被删除的模式字符的想法。 
5. 如果在使用跳过后再次发生不匹配，则该单词的匹配尝试失败。 
6. 循环之后，仅当整个单词已被消耗并且我们在模式中最多使用一次跳过时，匹配才有效，并且仅当模式中的任何剩余字符对应于单个允许的删除场景时，才可以安全地忽略它们。 
7. 如果任何一个词成功，我们立即返回“是”。 否则，在检查完所有单词后，我们返回“否”。 

### 为什么它有效

 核心约束是每个观察到的单词都是通过删除最多一个字符从原始单词派生出来的。 这意味着单词和“codecup”之间的对齐可能会以一种结构方式失败：模式中缺少一个字符。 两指针过程强制要求观察到的单词中的每个字符都必须对应于模式的保序子序列，而跳过计数器强制我们永远不会假设多个缺失位置。 这准确地描述了所有有效的腐败结果，并且排除替换或多重删除。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

TARGET = "codecup"

def matches(word):
    i = j = 0
    skipped = 0

    while i < len(word) and j < len(TARGET):
        if word[i] == TARGET[j]:
            i += 1
            j += 1
        else:
            if skipped == 1:
                return False
            skipped += 1
            j += 1

    if i != len(word):
        return False

    return True

def solve():
    n = int(input())
    words = input().split()

    for w in words:
        if matches(w):
            return "Yes"
    return "No"

print(solve())
```该解决方案将匹配逻辑隔离到辅助函数中，以便独立检查每个单词。 两指针循环确保在固定图案上进行线性扫描。 重要的微妙之处是最后检查整个单词是否被消耗； 否则，当单词中保留额外字符时，部分匹配可能会错误地通过。

 ## 边缘情况

 一个有用的失败案例是像“codecap”这样的词，它与目标在单个位置上有所不同，但通过替换而不是删除。 该算法从不允许字符替换，只在模式中跳过，因此它无法对齐不匹配的字符并正确拒绝它。 

另一个边缘情况是像“cdecp”这样的单词，它需要从原始“codecup”中删除多个字符。 跳过计数器可防止模式中出现多个不匹配，因此一旦需要第二个结构间隙，匹配就会立即失败。 

最后，短于 6 个字符的单词不能表示对最多 1 个删除的 7 个字符源的有效损坏。 指针逻辑自然会失败，因为必须跳过模式中的太多字符，超出了允许的单个删除。
