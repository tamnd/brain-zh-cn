 ## 解决方案
 ## 问题理解

 我们得到一个十进制字符串和一个操作计数`k`。 每个操作都会查找最左边出现的子字符串`"47"`。 

假设子串`"47"`从位置开始`x`使用从 1 开始的索引。 

如果`x`是奇数，我们将这两个数字替换为`'4'`， 所以`"47"`变成`"44"`。 

如果`x`是偶数，我们将这两个数字替换为`'7'`， 所以`"47"`变成`"77"`。 

如果字符串不包含`"47"`无论如何，该操作仍然消耗一步，但没有任何变化。 

任务是在恰好之后输出字符串`k`运营。 

这些约束完全塑造了解决方案。 字符串长度可以达到`10^5`，这对于线性扫描来说是可以管理的。 真正的困难在于`k`可以大到`10^9`。 如果每项操作的成本均等，则任何一项一项模拟操作的方法都会失败`O(1)`时间，因为十亿次迭代远远超出了时间限制。 

一个简单的实现将重复搜索第一个`"47"`并应用该规则。 搜寻费用`O(n)`，并且最多可以有`10^9`操作，所以最坏的情况变成`O(nk)`， 大约`10^14`运营。 即使优化搜索以避免重新扫描，仍然存在该过程可能持续大量步骤的问题。 

棘手的部分是转型可以创造新的`"47"`附近成对。 这个过程并不单调。 

考虑这个例子：```
4478
```第一个`"47"`从位置 2 开始，这是偶数，所以它变成`"77"`:```
4478 -> 4778
```现在一个新的`"47"`出现在位置1：```
4778 -> 4478
```该过程进入长度为 2 的循环。如果`k`很大。 

另一个微妙的情况是重叠效应。 

例子：```
34747
```最左边的`"47"`可能会消失，但改变数字可以立即创建另一个`"47"`与其相邻。 如果我们首先更新错误的一侧或未能仔细重新检查相邻位置，我们可以跳过有效的转换。 

第三种边缘情况是当活动`"47"`位于三字符模式的中间，例如`"447"`或者`"477"`。 

例如：```
447
```这`"47"`从位置 2 开始，该位置是偶数，因此：```
447 -> 477
```现在的`"47"`向左移动：```
477 -> 447
```我们再次得到无限的交替。 检测该结构是优化的关键。 

## 方法

 蛮力思想直接跟在陈述后面。 

对于每个操作：

 1. 从左到右扫描找到第一个`"47"`。 
2. 如果不存在，则停止更改字符串。 
3. 否则，应用奇偶规则。 

该模拟是正确的，因为它再现了问题中描述的确切过程。 问题是运行时间。 

单次扫描费用`O(n)`。 在最坏的情况下，我们可能会执行到`10^9`运营。 即使弦在许多实际情况下很快稳定下来，理论上的上限也是不可能的。 

关键的观察结果是每次操作期间只有一个局部区域发生变化。 更重要的是，一旦我们遇到某些模式，该过程就会变得周期性，周期为 2。 

看看当一个`"47"`出现在偶数位置：```
447 -> 477 -> 447 -> ...
```或者在一个奇怪的位置：```
474 -> 444 -> 447 -> 477 -> 447 -> ...
```经过短暂的瞬态阶段后，系统将永远在两种状态之间振荡。 

这意味着我们永远不需要模拟所有`k`运营。 我们只会模拟直到：

 1. 没有`"47"`遗迹。 
2. 我们检测振荡结构。 

一旦出现循环，剩下的操作就可以单独通过奇偶校验来解决。 

最优解维持最左边的当前位置`"47"`并在每次更改后仅更新附近的位置。 每次操作要么稍微移动活动位置，要么进入一个循环。 稳定之前真正不同状态的总数至多是线性的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nk) | O(nk) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将字符串转换为可变字符数组。 
2. 从左到右扫描一次，找到第一个出现的`"47"`。 
3.如果没有`"47"`如果存在，则立即打印该字符串，因为以后的操作不会执行任何操作。 
4. 否则，重复处理当前的`"47"`尽管`k > 0`。 
5. 假设该对从索引处开始`i`使用从 0 开始的索引。 

该问题使用从 1 开始的索引进行奇偶校验。 这意味着：

 -`i`偶数 → 位置为奇数
 -`i`奇数 → 位置为偶数
 6.如果`i`是偶数，将其变为`"44"`。 

此次替换后，只有附近的位置`i`可以创建一个新的`"47"`。 具体来说，一对新的可能会出现在`i-1`或保持在`i`。 
7.如果`i`是奇数，将这对改为`"77"`。 

同样，只有附近的位置才重要。 
8. 在继续之前，检查我们是否进入了振荡配置。 

危险的情况是：

 - 在下一个数字为偶数位置时替换`'7'`- 在前一个数字为奇数位置时替换`'4'`这些模式立即创建 2 个周期。 
9. 当检测到这样的循环时，最终状态仅取决于剩余操作次数是奇数还是偶数。 
10. 否则，继续在本地更新当前位置，而不是重新扫描整个字符串。 

### 为什么它有效

 不变的是每次操作后只有一个连续的局部区域可以改变。 更换`"47"`和`"44"`或者`"77"`最多影响大多数相邻对，因此最左边的`"47"`只能停留在附近或移动一个位置。 

振荡检测是正确的，因为变换变成确定性的二态循环。 一旦我们达到这样的配置，每两个操作都会恢复相同的字符串。 剩下的效果仅取决于奇偶校验，这让我们可以安全地跳过潜在的数十亿次操作。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = list(input().strip())

    i = 0
    while i + 1 < n and not (s[i] == '4' and s[i + 1] == '7'):
        i += 1

    if i + 1 >= n:
        print("".join(s))
        return

    while k > 0 and i + 1 < n:
        if s[i] != '4' or s[i + 1] != '7':
            i += 1
            while i + 1 < n and not (s[i] == '4' and s[i + 1] == '7'):
                i += 1
            continue

        k -= 1

        if i % 2 == 0:
            s[i + 1] = '4'

            if i + 2 < n and s[i + 2] == '7':
                if k % 2 == 1:
                    s[i + 1] = '7'
                break

        else:
            s[i] = '7'

            if i - 1 >= 0 and s[i - 1] == '4':
                if k % 2 == 1:
                    s[i] = '4'
                break

            i -= 1

    print("".join(s))

solve()
```解决方案首先找到第一个`"47"`一对。 如果不存在，则字符串已经稳定。 

主循环始终在当前最左边工作`"47"`。 奇偶校验小心地使用基于 0 的索引。 指数`0`对应位置`1`，这在问题陈述中很奇怪。 

当该对从奇数的 1 位置开始时，只有第二个数字从`'7'`到`'4'`。 当它从偶数 1 开始的位置开始时，只有第一个数字从`'4'`到`'7'`。 

周期检测是微妙的部分。 

假设我们处理：```
447
```这`"47"`从索引开始`1`，对应于偶数位置`2`。 我们改造：```
447 -> 477
```现在另一个`"47"`立即出现在左侧。 字符串在这两种状态之间永远交替。 

我们没有模拟所有剩余的操作，而是使用奇偶校验：

 - 奇数剩余操作应用一次额外的翻转
 - 即使剩余的操作也保持当前状态不变

 该实现每次操作只修改一位数字。 这避免了不必要的工作并使总复杂度保持线性。

```| 步骤| 当前字符串 | 最左边`"47"`| 行动|

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个位置仅被处理固定次数 |
 | 空间| O(n) | 可变字符数组存储字符串 |

 该算法很容易满足限制。 线性传递`10^5`字符对于 Python 来说是微不足道的，并且循环快捷方式可以防止依赖`k`，即使当`k = 10^9`。

 ## 边缘情况

 考虑输入：```
3 100
447
```第一个`"47"`从位置 2 开始，该位置是偶数。 

序列变为：```
447 -> 477 -> 447 -> ...
```该算法检测到这一点是因为转弯后`"47"`进入`"77"`，有一个`'4'`紧接在修改位置之前。 这保证了 2 个周期。 由于剩余操作数是偶数，因此最终状态保持不变`"447"`。 

现在考虑：```
4 5
1234
```不`"47"`最初存在。 该算法在初始扫描后完成并立即返回原始字符串。 一个幼稚的实现，继续循环所有`k`操作会不必要地浪费时间。 

最后，考虑：```
5 3
47474
```第一个操作更改最左边的对：```
47474 -> 44474
```现在一个新的`"47"`稍后出现：```
44474 -> 44774
```然后该过程进入围绕中间子串的循环。 该算法可以正确处理这个问题，因为每次修改后它只需要检查相邻位置。 无效`"47"`可能会突然出现在远离编辑区域的地方。
