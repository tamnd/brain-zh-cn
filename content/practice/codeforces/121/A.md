 ## 解决方案
 ## 问题理解

 我们需要计算一个区间内的总和`[l, r]`。 对于每个整数`x`在这个范围内，我们计算`next(x)`， 在哪里`next(x)`表示大于或等于的最小幸运数字`x`。 

幸运数字是一个正整数，其小数位数仅`4`和`7`。 例子是`4`,`7`,`44`,`47`,`74`,`77`， 等等。 

任务不是数幸运数字。 我们必须将区间内每个整数的下一个幸运数字的值相加。 

例如，如果`l = 2`和`r = 7`:

 -`next(2) = 4`-`next(3) = 4`-`next(4) = 4`-`next(5) = 7`-`next(6) = 7`-`next(7) = 7`答案是`4 + 4 + 4 + 7 + 7 + 7 = 33`。 

限制非常小。 间隔本身可能很大，因为`r`可能达到`10^9`，因此迭代每个值`l`到`r`在最坏的情况下是不可能的。 对于 2 秒的时间限制来说，超过 10 亿个数字的循环将花费太长的时间。 

同时，幸运数字数量高达`10^9`很小。 这里的幸运数字最多有10位，每个数字只有2个选择，`4`或者`7`。 这意味着总计数为：`2^1 + 2^2 + ... + 2^10 = 2046`使用几千个值是微不足道的。 整个问题都是围绕利用这个差距而设计的。 

一些边缘情况可能会悄无声息地破坏粗心的实现。 

考虑：```
4 4
```答案是`4`， 因为`next(4) = 4`。 一个有缺陷的实现，它搜索严格大于的第一个幸运数字`x`会错误地使用`7`。 

另一个棘手的情况是当间隔跨越多个幸运数字范围时：```
5 8
```正确的贡献是：

 -`5,6,7 -> 7`-`8 -> 44`所以答案是：```
7 + 7 + 7 + 44 = 65
```天真的分组实现很容易忘记处理间隔内最后一个幸运数字之后的尾部。 

大的边界也很重要：```
999999999 1000000000
```这两个值的下一个幸运数字是`4444444444`，这超过了`10^9`。 如果我们只生成最多幸运数字`10^9`，我们完全错过了正确答案。 

## 方法

 蛮力的想法很简单。 对于每个整数`x`从`l`到`r`，生成或搜索大于或等于的最小幸运数`x`，然后将其添加到答案中。 

这在逻辑上是有效的，因为总和的定义是直接的。 问题是性能。 在最坏的情况下，间隔长度接近于`10^9`。 甚至一个`O(1)`每个值的操作已经太慢了。 

幸运数字的结构为我们提供了更好的路径。 的价值`next(x)`在整个范围内保持恒定。 

例如：

 | x 范围 | 下一个(x) |
 | ---| ---|
 | 1..4 | 1..4 4 |
 | 5..7 | 5..7 7 |
 | 8..44 | 8..44 44 | 44
 | 45..47 | 45..47 47 | 47

 我们可以分块处理这些范围，而不是单独处理每个整数。 

关键的观察是，一旦我们知道幸运数字的排序列表，两个连续幸运数字之间的每个间隔都会重复贡献相同的值。 

假设当前的幸运数字是`44`，之前的幸运数字是`7`。 然后每个数字从`8`通过`44`贡献`44`。 

这意味着我们只需要：

 1. 生成所有幸运数字。 
2. 对它们进行排序。 
3. 浏览幸运数字并计算其中有多少`[l, r]`分为各个部分。 

由于幸运数字只有大约两千个，所以这个解决方案速度非常快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(r - l + 1) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(2^10) | O(2^10) | O(2^10) | O(2^10) | 已接受 |

 ## 算法演练

 1. 使用递归生成每个最多 10 位数字的幸运数字。 

在每个步骤中，附加`4`或者`7`到当前号码。 这探索了幸运数字结构的完整二叉树。 
2. 将所有生成的幸运数字存储在一个列表中。 

我们包括大于的值`10^9`因为`next(x)`对于接近上限的数字可能会超过`10^9`。 
3. 对幸运数字进行排序。 

递归生成自然不能保证排序顺序。 
4.初始化：

 -`ans = 0`-`cur = l`变量`cur`跟踪间隔中尚未处理的第一个值。 
5. 按升序遍历幸运数字。 

对于每个幸运数字`v`：

- 如果`v < cur`，跳过它，因为它的部分已经在我们后面了。 
- 否则，间隔从`cur`最多`min(r, v)`都有`next(x) = v`。 
6. 计算有多少个数字属于该段。 

计数为：$\text{count}=\min(r,v)-cur+1$7. 添加该部分的贡献。$\text{contribution}=v \times \text{count}$8. 移动`cur`到该段之后的第一个未处理的值。 

放：```
cur = v + 1
```9.停一次`cur > r`。 

现在已经考虑了间隔中的每个值。 

### 为什么它有效

 该算法依赖于幸运数字对数轴的划分。 

为了一个幸运数字`v`，每个整数严格大于前一个幸运数字并且至多`v`有`next(x) = v`。 

这些片段是不相交的，并且一起覆盖了整个区间`[l, r]`。 

在迭代过程中，`cur`始终指向第一个未处理的整数。 当我们处理一个幸运数字时`v`，我们将下一个幸运数字等于的所有整数的贡献精确相加`v`。 进阶后`cur`到`v + 1`, no processed value is revisited.

 因为中的每个整数`[l, r]`恰好属于一个这样的段，则最终的总和是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

l, r = map(int, input().split())

lucky = []

def gen(x):
    if x > 10**10:
        return

    if x > 0:
        lucky.append(x)

    gen(x * 10 + 4)
    gen(x * 10 + 7)

gen(0)

lucky.sort()

ans = 0
cur = l

for v in lucky:
    if cur > r:
        break

    if v < cur:
        continue

    right = min(r, v)
    cnt = right - cur + 1

    ans += v * cnt
    cur = right + 1

print(ans)
```递归生成器通过重复附加来构建每个幸运数字`4`和`7`。 

开始于`0`很方便，因为：

 -`0`本身不被存储。 
- 它的孩子成为`4`和`7`。 

递归深度很小，最多10级，因此这里递归是完全安全的。 

停止条件使用`10^10`而不是`10^9`。 这是微妙但必要的。 如果`x = 10^9`，它的下一个幸运数字实际上是`4444444444`，不是下面的某个值`10^9`。 

排序后，主循环按升序处理幸运数字。 对于每个幸运数字`v`, 区间`[cur, min(r, v)]`贡献`v`。 

该行：```
cnt = right - cur + 1
```很容易出错。 区间两端都包含在内，所以我们需要`+1`。 

另一个微妙的点是：```
cur = right + 1
```不是`v + 1`。 

认为`r < v`。 然后仅使用该段的一部分。 直接进阶至`v + 1`仍然符合逻辑，但使用`right + 1`与实际处理的边界相符，避免以后修改代码时出现错误。 

Python 整数自动处理大值，这很重要，因为答案可能超出 32 位整数范围。

 ## 边缘情况

 考虑输入：```
4 4
```该算法开始于`cur = 4`。 

当达到幸运数字时`4`，它处理范围：```
[4, min(4, 4)] = [4, 4]
```贡献是：```
4 * 1 = 4
```然后`cur`变成`5`，结束循环。 输出是正确的，因为`next(4)`是`4`， 不是`7`。 

现在考虑：```
5 8
```相关的幸运数字是`7`和`44`。 

该算法处理：

 -`5..7`使用价值`7`-`8..8`使用价值`44`所以答案就变成了：```
7 + 7 + 7 + 44 = 65
```这证实了幸运数字范围之间的转换已正确处理。 

最后，检查：```
999999999 1000000000
```两个值之后的下一个幸运数字是`4444444444`。 

当迭代达到该幸运数时，处理的范围为：```
999999999..1000000000
```有计数`2`。 

贡献变为：```
2 * 4444444444 = 8888888888
```这说明了为什么产生的幸运数字超出了`10^9`是必要的。
