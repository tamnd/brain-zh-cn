 ## 解决方案
 ## 问题理解

 SwerChat 显示的列表按新近度排序。 最近在线的成员出现在最前面，第二个最近在线的成员出现在第二位，依此类推。 

9:00，Beppa 记录订单`a`。 22:00，她又记录了一份订单`b`。 

在这两个时刻之间，唯一可以改变顺序的是会员上线。 由于没有人同时在线，因此每次都会处理一个在线事件。 当成员上线时，他们将成为最近见过的成员，因此他们会移动到列表的前面。 

我们必须确定必须至少在线一次的不同成员的最小数量，才能将排序从`a`进入`b`。 

所有测试用例的总大小最多为`10^5`，因此任何比较所有成员对或重复模拟大型列表操作的解决方案都会太慢。 一个`O(n)`或者`O(n log n)`每个测试用例的解决方案很容易足够快。 

微妙之处在于，成员可能会出现在不同的位置，而不必在线。 当其他人上网时，它们可能会被推迟。 如果将每个立场发生变化的人都计算在内的话，就会高估答案。 

考虑：```
a = [1, 2, 3]
b = [2, 1, 3]
```唯一会员`2`需要上网。 成员`1`改变位置，但永远不必在线。 

另一个容易犯的错误是假设两个排列之间的每个反转都对应于一个在线事件。 

例如：```
a = [1, 2, 3, 4]
b = [3, 4, 1, 2]
```会员`3`和`4`可以上线，生成最终订单。 答案是`2`， 不是`4`。 

当列表已经相同时，会出现不同的边缘情况：```
a = [1, 2, 3, 4]
b = [1, 2, 3, 4]
```没有人需要上网，所以正确答案是`0`。 

## 方法

 暴力的观点是猜测哪些成员在线并检查某些前移操作序列是否可以产生`b`。 

这个想法原则上是正确的，但完全不切实际。 有`2^n`可能的成员子集，甚至验证一个候选子集也需要模拟列表操作。 和`n`最多`10^5`，这是不可能的。 

关键的观察结果来自于对**从不在线**的成员的观察。 

假设某个成员从未上线。 他们永远不会被移到前面。 他们唯一可能发生的事情就是其他成员跳到他们前面。 

因此，所有从不在线的成员都保持原始排列中的相对顺序`a`。 

这意味着最终名单`b`有一个非常具体的结构：```
[ all members who were online ]
[ all members who were never online ]
```第二部分必须以与中完全相同的相对顺序出现`a`。 

为了最大限度地减少在线会员的数量，我们希望最大限度地增加从不在线的会员的数量。 

让`pos[x]`担任会员的职位`x`在`a`。 

替换每个元素`b`通过其在`a`。 

例如：```
a = [1, 4, 2, 5, 3]

pos:
1 -> 1
4 -> 2
2 -> 3
5 -> 4
3 -> 5

b = [4, 5, 1, 2, 3]

positions in a:
[2, 4, 1, 3, 5]
```从不在线的成员必须形成后缀`b`，以及他们在`a`必须严格递增。 这正是保持相对秩序的条件。 

所以我们需要严格递增的变换序列的最长后缀。 

如果该后缀有长度`L`， 然后`L`会员可能永远不在线，答案是：```
n - L
```### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取排列`a`。 
2. 构建数组`pos`在哪里`pos[x]`存储成员的位置`x`在`a`。 
3. 遍历`b`从右到左。 
4. 维持当前检查的后缀的不变量`b`对应于严格递增的位置序列`a`。 
5. Starting from the end, continue moving left while:```
pos[b[i-1]] < pos[b[i]]
```这意味着这些成员的相对顺序与`a`，所以他们可能都永远不在线。 
6. 这个条件首先不成立的地方是在线前缀和从不在线后缀之间的边界。 
7. 如果递增后缀从索引开始`s`，那么它的长度是`n - s`。 
8. 输出：```
s
```因为正是第一个`s`的成员`b`必须属于在线集。 

### 为什么它有效

 每个从不上线的成员都会保留其相对顺序`a`。 由于所有在线成员最终都在所有从不在线成员之前，因此从不在线成员必须形成后缀`b`。 

后缀为`b`保留相对顺序`a`正是当相应的位置`a`严格增加。 任何更长的后缀都会违反此条件，并且不能完全由从不在线的成员组成。 

相反，如果后缀在增加，我们可以通过声明该后缀之前的所有成员都在线来实现排列。 按照在线成员的顺序从右到左处理这些在线成员`b`，将每个移动到前面一次。 这会准确产生所需的前缀，同时使后缀保持其原始的相对顺序。 

因此，最长的递增后缀给出了最大可能数量的从不在线成员，这最小化了在线成员的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        pos = [0] * (n + 1)

        for i, x in enumerate(a):
            pos[x] = i

        s = n - 1

        while s > 0 and pos[b[s - 1]] < pos[b[s]]:
            s -= 1

        answers.append(str(s))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```这`pos`array 将相对顺序问题转换为简单的整数比较。 而不是反复寻找里面的成员`a`，我们可以在常数时间内检查订单保存情况。 

变量`s`跟踪最长有效后缀的开头。 我们从末尾开始，因为每个长度为 1 的后缀都会自动增加。 

条件```
pos[b[s - 1]] < pos[b[s]]
```检查将后缀向左扩展一位是否仍然保留顺序`a`。 

当条件失败时，我们找到了最大可能的不在线后缀。 答案正是它之前的元素数量，即`s`。 

不需要列表模拟。

 ## 边缘情况

 考虑已经排序的情况：```
1
4
1 2 3 4
1 2 3 4
```变换后的位置序列为：```
[0, 1, 2, 3]
```每个相邻的比较都在增加，因此后缀扩展到整个数组。 算法返回`0`，正确识别没有人必须上网。 

现在考虑一种只有一名成员在线的情况：```
1
3
1 2 3
2 1 3
```变换后的序列为：```
[1, 0, 2]
```从末尾开始扫描：```
0 < 2   -> valid
1 < 0   -> invalid
```最长的递增后缀从索引开始`1`，所以答案是`1`。 成员`2`上线并移动到前面，同时`1`和`3`保持离线状态。 

最后，考虑高度打乱的排序：```
1
5
1 2 3 4 5
5 4 3 2 1
```变换后的序列为：```
[4, 3, 2, 1, 0]
```右边的第一个比较已经失败，因此最长的递增后缀有长度`1`。 算法返回`4`，这意味着四个成员必须属于在线集。 这是可能的最小值，因为没有更大的后缀可以保留原始的相对顺序。
