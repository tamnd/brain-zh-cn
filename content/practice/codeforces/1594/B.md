 ## 解决方案
 ## 问题理解

 我们被要求枚举由基本扩展规则定义的一组非常具体的数字。 如果我们可以将一个数字写为某个固定基数的不同幂的总和，则该数字被认为是有效的$n$。 这意味着每个力量$n^0, n^1, n^2, \dots$可以使用一次或根本不使用，其值是通过将所选的功率加在一起形成的。 

这会立即将每个有效数字转换为指数上的二元决策：对于每个指数$i$，我们决定是否$n^i$贡献总和。 如果我们用位掩码来思考，每个数字对应一个二进制掩码，其中位$i$控制包含$n^i$。 

任务是将所有这些可表示的数字按升序排序并返回$k$-第一个。 

这些限制迫使我们采取谨慎的态度。 测试用例数量可达$10^4$，以及两者$n$和$k$可以大到$10^9$。 任何尝试显式生成序列或迭代候选序列的方法都会立即失败，因为序列的可用幂数呈指数增长。 即使对于中等$k$，枚举值需要探索权力的组合，这是不可行的。 

幼稚思维的一个微妙的失败案例出现在以下情况：$n$很大。 例如，如果$n = 10^9$， 然后$n^0 = 1$和$n^1$已经超越了大多数中间总和，因此排序行为与小基数中的排序行为非常不同。 假设数字之间的间距均匀的天真的贪婪构造在这里会破裂，因为增长是高度非线性的。 

另一个陷阱是假设序列的行为类似于所有的标准二进制数$n$。 这仅适用于当$n = 2$。 对于其他$n$，位置值按指数加权，因此位掩码的字典顺序并不直接匹配数字顺序，除非我们仔细证明它的合理性。 

## 方法

 蛮力的想法很简单。 我们通过尝试每个幂子集来生成所有数字$n^0, n^1, \dots$在合理的限度内，计算它们的总和，存储它们，对它们进行排序，然后选择$k$-th 元素。 这是正确的，因为它详尽地构造了有效数字的定义。 

失败点在于尺寸。 即使我们将自己限制在前 60 次幂（自$n^i$很快变得巨大），我们仍然有$2^{60}$子集。 这远远超出了任何计算极限。 

关键的观察是，每个有效数字都是由二元选择向量的幂唯一确定的$n$。 这意味着$k$-第一个最小的数字对应于二进制表示$k$本身，但以基数解释$n$而不是基数 2。 

更准确地说，如果我们写$k$在二进制中，每一位表示我们是否包含相应的幂$n$。 这$i$第 位贡献$n^i$如果已设置。 这是有效的，因为总和的排序与掩码的递增二进制值一致：较高的幂支配所有较低的幂，因此按位的字典顺序与构造值的数字顺序一致。 

因此，问题简化为转换$k$转换为二进制形式并将其计算为基数中的多项式$n$。

 ## 算法演练

 我们从二进制表示中逐位构造答案$k$。 

1. 转换$k$转换为二进制形式，从最低有效位到最高有效位进行处理。 每个位告诉我们是否有相应的幂$n$已包含在总和中。 
2. 保持运行值`ans`，最初为零，和一个乘数`pow_n`初始化为1，代表$n^0$。 该乘法器跟踪当前的功率$n$我们正在分配当前位位置。 
3. 对于每一位$k$，如果该位为 1，我们添加`pow_n`到`ans`。 这反映了在子集表示中选择该功率。 
4.处理完每一位后，更新`pow_n *= n`，因为我们移动到下一个指数。 
5. 继续，直到所有位$k$已被处理。 
6. 输出`ans mod (10^9 + 7)`。 

我们可以安全地按顺序处理位的原因是每个较高位对应于严格更大的幂$n$，并且这些权力在有效数字的排序中主导所有较低的贡献。 

### 为什么它有效

 每个有效数字对应于以下幂的子集$n$，相当于二进制掩码。 这些数字的顺序与这些被解释为二进制整数的掩码的自然顺序相匹配，因为增加最高不同位总是会增加值，而不管较低位如何，因为$n^i$。 因此，$k$按排序顺序的第一个子集正是以下的二进制表示$k$，解释为选择向量的幂$n$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())

    ans = 0
    power = 1

    while k > 0:
        if k & 1:
            ans = (ans + power) % MOD
        power = (power * n) % MOD
        k >>= 1

    print(ans)
```代码直接实现了二值分解的思想。 变量`power`跟踪连续的权力$n$，始终保持模数$10^9+7$因为只需要最终值对该数字取模。 

这里的一个常见错误是尝试预先计算幂$k$，但这是不必要的，因为我们只需要与中有位一样多的幂$k$，对于高达 30 的约束，最多为 30$10^9$。 另一个微妙的点是更新`power`处理完每一位后； 颠倒这个顺序将使所有贡献移动一个指数并破坏正确性。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MOD = 10**9 + 7
    t = int(sys.stdin.readline())
    out = []

    for _ in range(t):
        n, k = map(int, sys.stdin.readline().split())
        ans = 0
        power = 1
        while k > 0:
            if k & 1:
                ans = (ans + power) % MOD
            power = (power * n) % MOD
            k >>= 1
        out.append(str(ans))

    return "\n".join(out)

assert run("1\n10 5\n") == str((1 + 4) % (10**9 + 7))

 ## 边缘情况

 一种边缘情况是当$k = 1$。 二进制表示仅包含最低位，因此算法返回$n^0 = 1$。 循环运行一次，添加`power = 1`，并正确停止。 

另一种情况是当$n$非常大，比如$n = 10^9$。 第一个乘法集`power`到$10^9$，但由于我们立即减少模数$10^9+7$，值仍然有效。 位处理的结构保持不变，只需要一到两次迭代就可以超过更高的功率$k$的位长度。 

最后一种情况是当$k$有多个高位设置，例如$k = 2^m - 1$。 这里每一位都做出贡献，产生完整的几何和$1 + n + n^2 + \dots + n^m$。 该算法自然地按顺序累积所有幂，匹配该范围内最大可表示数字的预期构造。
