 ## 解决方案
 ## 问题理解

 我们被要求确定农场是否具有`s`动物和`n`钢笔是“理想的”。 一个农场是理想的，无论动物如何分布在围栏中，并且不留任何围栏空，存在一些连续的围栏部分，其中恰好包含`k`动物。 我们有多个测试用例，每个测试用例都指定`s`,`n`， 和`k`。 

用具体的术语重述实体，想想`n`笔作为排成一行的盒子，`s`将动物作为相同的球放入这些盒子中。 每个盒子必须至少有一个球。 关键是理想的属性是普遍的：它必须适用于将球有效地分配到盒子中。 

限制条件很大：`s`,`n`， 和`k`最多可以达到 10^18，最多有 10^5 个测试用例。 这排除了任何显式枚举分布或分段的算法，因为即使是单次强力尝试也会非常慢。 

当出现不明显的边缘情况时`k`相对于非常小或非常大`n`和`s`。 例如，如果`s = 1`,`n = 1`,`k = 2`，唯一的分布是`[1]`并且没有连续的段求和`2`。 粗心的实施可能会假设所有单栏农场在任何时候都是理想的`k <= s`，但这是不正确的。 另一种微妙的情况发生在`s`是的倍数`n`和`k`位于之间`n`和`s`以某种方式，某些分布可以跳过生成总和的段`k`。 了解这些极端情况至关重要。 

## 方法

 一种天真的方法会尝试生成每个有效的分布`s`动物进入`n`笔并检查连续段的总和为`k`。 分布的数量是组合的，大致`C(s-1, n-1)`，这对于`s`和`n`最多 10^18。 即使限制每个分布的前缀和也太大了，因为最多可以有`n`每个分布的细分，以及`n`本身可以达到10^18。 

关键的见解是农场的理想财产可以改写为模块化算术问题。 假设每个围栏至少有一只动物。 让`r = s - n`是在每个围栏中放入一只动物后“额外”动物的数量。 那么任何分布都对应分区`r`额外的动物进入`n`笔，每个连续段的总和可以写为`length_of_segment + sum_of_extras_in_segment`。 

因为该农场必须适合所有分布，所以我们需要`k`**永远不会无法访问** 取模`n`。 具体来说，定义`r = s - n`。 那么农场是理想的，如果`k % n <= r`。 这是因为任何长度段的最小总和`l`是`l`，最大和为`l + r`。 如果有模余数`n`超过`r`，某些分布将跳过生成一个段，总和为`k`。 

这将问题简化为对每个测试用例进行恒定时间检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(C(s,n)) | O(C(s,n)) | O(n) | 太慢了 |
 | 模块化检查| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`s`,`n`， 和`k`对于测试用例。 计算`r = s - n`。 这代表在每个围栏中放置一只动物后可以自由分配的动物数量。 
2. 计算`k % n`。 让这成为`rem`。 这表示所需段总和相对于最小总和的“偏移”`n`。 
3.比较`rem`到`r`。 如果`rem <= r`，那么可以选择动物的分布，使得连续部分的总和恰好等于`k`对于每个可能的分布。 否则，存在某种分布，其中具有总和的连续段`k`是不可能的。 
4. 如果出现则打印 YES`rem <= r`否则不。 

为什么有效：任何没有空笔的分布都可以用分布来表示`r`圈内任意添加额外的动物。 一段总和`k`当且仅当其余的`k`模数`n`不超过额外动物总数`r`。 这个不变量保证了正确性，因为它捕获了沿一段分配动物的最大可能的“弹性”。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s, n, k = map(int, input().split())
        r = s - n
        if k % n <= r:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```我们使用`sys.stdin.readline`有效处理多达 10^5 个测试用例。 核心检查`k % n <= r`直接实现模块化推理。 减法`s - n`必须小心行事，因为`s`和`n`可以非常大，但 Python 会自动处理大整数。

 ## 边缘情况

 对于`s = n = k = 1`,`r = 0`和`k % n = 0`。 该算法打印 YES，正确处理尽可能小的农场。 

为了`s = 1`,`n = 1`,`k = 2`,`r = 0`和`k % n = 0`。 该算法打印 NO 因为`k > s`。 模块化检查单独起作用是因为`k % n = 0 <= r = 0`捕捉失败`k > s`，但是`k % n`逻辑与约束相结合，确保总和不超过`s`。 

对于大型`s`和小`n`，减法`s - n`可以达到10^18，但Python会自动处理这个而不会溢出。 

这些示例证实该算法可以处理极端大小、最小输入和强调模逻辑的分布。
