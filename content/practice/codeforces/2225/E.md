 ## 解决方案
 ## 问题理解

 我们在二维整数网格上得到一组点。 这些观点并不是敌对的； 相反，它们来自于一个大的轴对齐正方形内的随机过程。 我们的任务是放置固定半径的圆$r$，具有整数中心，这样大多数点都被覆盖。 

如果一个点位于圆内部或恰好位于其边界上，则圆覆盖该点。 我们可以放置多个圆圈，但它们的面积不能重叠。 允许接触，但禁止任何正区域交叉，这实际上迫使中心至少$2r$相距欧几里得距离。 

目标不是覆盖所有点，只是至少覆盖$89\%$。 这种容差很重要，因为它建议采用基于密度或概率的策略，而不是精确的几何填充。 

输入大小可达$n = 10^4$。 任何$O(n^2)$几何比较策略是边缘策略，但如果常数因子很小，则可能会通过。 然而，预期的解决方案必须避免成对的循环交互或全局优化。 

一个微妙的约束是在比圆形区域大得多的正方形内随机均匀生成。 这意味着点在区域中自然聚集，但也存在孤立点。 存在有效解决方案的保证消除了穷举搜索的需要，但并没有告诉我们如何确定性地找到它。 

一个幼稚的错误是假设我们需要以最佳方式对点进行聚类，例如使用 k 均值样式分组或贪婪最大磁盘。 这些方法可能会失败，因为最优聚类在局部决策下不稳定并且变得昂贵。 

另一个常见的失败是尝试贪婪地为每个点放置一个圆，然后解决重叠问题。 但这会失败，因为重叠解析变得全局并且可能级联，从而破坏正确性。 

一个更简单的错误是假设我们必须最大化每个圆的覆盖范围。 该问题不需要最优打包，只需要阈值覆盖，因此基于粗网格的策略就足够了。 

## 方法

 暴力解释是考虑边界框中每个可能的整数中心并评估有多少点位于距离内$r$。 然后贪婪地挑选最好的中心，删除被覆盖的点，然后重复。 

这在概念上是可行的，因为每一步都会选择一个局部最优的圆，但在计算上是不可行的。 候选中心的数量为$O(X^2)$在哪里$X$可以达到$10^5$，放弃$10^{10}$候选人。 即使将候选人限制为点坐标仍然会产生$O(n^2)$在最坏的情况下检查每次迭代，导致$10^8$到$10^9$距离计算。 

关键的结构观察来自随机均匀分布和弱覆盖要求。 因为至少$89\%$必须被覆盖，我们只需要找到密集区域，而不是全局最优簇。 在均匀随机的正方形中，点自然会形成局部波动，其中某些区域包含的点明显多于平均值。 任何足够密集的区域都可以被圆捕获。 

我们不是连续搜索，而是使用单元大小与$r$。 任意半径的圆$r$可以与一组有界的网格单元相关联，并且任何密集簇在其内部的一个点附近都会有一个代表中心。 

因此，我们将问题简化为仅在现有点位置扫描候选中心。 对于每个未覆盖的点，我们计算距离内有多少个仍未覆盖的点$r$。 如果此计数超过阈值，我们会在那里放置一个圆圈并删除这些点。 

重叠限制是通过删除点来隐式处理的：一旦放置了一个圆，我们就不会将另一个圆放置得太近，因为该区域中的点消失了，并且未来的候选点自然会发生变化。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力以网格为中心 |$O(X^2 n)$|$O(n)$| 太慢了 |
 | 成对贪婪聚类|$O(n^2)$|$O(n)$| 风险/边缘 |
 | 以点为中心的贪婪覆盖 |$O(n^2)$最糟糕的是，$O(n \log n)$平均 |$O(n)$| 已接受 |

 ## 算法演练

 我们依靠具有空间修剪的点中心的贪婪聚类策略。 

1. 将所有点视为最初未被覆盖的点，并将它们存储在动态结构中，通常是列表或集合。 
2. 当未覆盖点的数量大于$11\%$的$n$，尝试找到一个好的圆心：

 对于每个候选点$p_i$，计算距离内有多少个未覆盖的点$r$。 这是使用平方欧几里德距离来完成的，以避免浮点错误。 

其工作原理是，任何有效的解决方案都必须至少有一个圆覆盖剩余未覆盖点的密集子集，并且这些点之一可以充当其中心近似值。 
3. 选择覆盖次数最多的点。 如果这个最大值很小，则意味着剩余的未覆盖点已经稀疏并且在允许的范围内$11\%$临界点。 
4. 以该选定点为中心放置一个圆，并标记半径内的所有点$r$如所覆盖。 
5. 重复直到满足停止条件。 

关键的优化是我们没有明确地将圆维护为彼此交互的几何对象。 相反，覆盖范围纯粹通过点删除来管理，这在实践中自动强制执行非重叠，因为任何重叠的圆都需要重叠的未覆盖点，而这些点已不存在。 

### 为什么它有效

 该算法维护一组不断缩小的未覆盖点。 每个放置的圆都会删除以代表性位置为中心的密集点邻域。 由于与圆大小相比，输入在较大区域中是均匀随机的，因此密集簇始终存在，直到大多数点被删除。 

不变的是，每次迭代后，所有剩余的未覆盖点都位于先前选择的密集区域之外。 由于每次迭代都会删除大部分局部密度，因此未覆盖的集合会迅速缩小。 该过程在跌至以下之前停止$11\%$，保证满足要​​求$89\%$覆盖范围得到满足。 

随机分布保证确保大到足以阻碍进展的病态稀疏配置以高概率不存在，并且有效解决方案的存在意味着这种密集选择始终存在。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, r = map(int, input().split())
    pts = [tuple(map(int, input().split())) for _ in range(n)]
    
    r2 = r * r
    alive = [True] * n
    remaining = n
    centers = []

    def count_covered(i):
        x1, y1 = pts[i]
        cnt = 0
        for j in range(n):
            if alive[j]:
                x2, y2 = pts[j]
                dx = x1 - x2
                dy = y1 - y2
                if dx * dx + dy * dy <= r2:
                    cnt += 1
        return cnt

    while remaining > (11 * n) // 100:
        best_i = -1
        best_cnt = 0

        for i in range(n):
            if not alive[i]:
                continue
            cnt = count_covered(i)
            if cnt > best_cnt:
                best_cnt = cnt
                best_i = i

        if best_i == -1 or best_cnt == 0:
            break

        centers.append(pts[best_i])

        x0, y0 = pts[best_i]
        for i in range(n):
            if alive[i]:
                x, y = pts[i]
                dx = x - x0
                dy = y - y0
                if dx * dx + dy * dy <= r2:
                    alive[i] = False
                    remaining -= 1

    print(len(centers))
    for x, y in centers:
        print(x, y)

if __name__ == "__main__":
    solve()
```该解决方案重复选择覆盖最大数量的尚未覆盖的点的点。 功能`count_covered`通过扫描所有点来计算覆盖范围，主循环贪婪地选择最佳候选点。 

移除步骤至关重要，因为它确保一旦某个区域被覆盖，就不会影响后续决策，从而防止同一区域出现多余的圆圈。 

终止条件直接编码了至少覆盖的要求$89\%$点。

 ## 边缘情况

 一种边缘情况是所有点都已在单个半径内。 在这种情况下，第一个选择的中心覆盖了所有内容，并且循环立即停止，因为剩余比率低于阈值。 贪心选择自然会选择任何点作为中心，因为所有点都具有相同的覆盖范围。 

另一种情况是点均匀分布，因此没有单个点具有大的覆盖范围。 然后每次迭代仅删除少量点，但一旦满足 89% 阈值，循环就会停止。 该算法从不尝试强制完全覆盖，从而避免了不必要的循环。 

第三种情况是远离任何集群的孤立异常值。 这些点仍然未被覆盖，但它们落在允许的 11% 松弛范围内，因此算法终止而不尝试覆盖它们，从而满足问题要求。
