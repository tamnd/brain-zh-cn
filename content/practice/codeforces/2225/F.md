 ## 解决方案
 ## 问题理解

 给定一个字符串，我们可以将它分成几个连续的部分。 每一块必须至少有长度`l`，并且我们需要至少生产`k`总共件数。 

选择有效的剪辑后，所有生成的片段都会按字典顺序排序。 在该排序列表中，我们只关注出现在位置上的元素`k`。 任务是选择切割位置，以便`k`- 按字典顺序，第最小的部分尽可能大。 

关键的交互是我们不会直接优化所有部分，而只会优化最终排名的部分`k`排序后。 这使得问题不对称：大多数棋子仅在影响目标棋子的排名时才重要。 

这些约束迫使我们在每个测试用例中采用线性或近线性行为。 由于所有测试用例的总长度最多为一百万，因此任何尝试所有剪切或在嵌套循环内执行重复子字符串比较的解决方案都将无法生存。 甚至一个$O(n \log n)$每个测试用例的方法只有在实践中接近线性并且避免大量子字符串复制时才是可接受的。 

当贪婪切割尝试在本地最大化目标块但意外更改其他块的多重集以使目标的排名发生变化时，就会出现微妙的失败情况。 例如，如果我们过早地剪切，我们可能会创建许多按字典顺序排列的小片段，这会人为地将我们所需的片段按排序顺序进一步向下推。 

另一个不明显的问题是子串比较成本。 在排序或二分搜索过程中重复比较子字符串的简单方法会在重复的前缀上退化为二次行为，例如`"aaaaaa...."`。 

## 方法

 蛮力观点是将问题视为在`n - 1`间隙，受每个段至少长度的约束`l`并且段数至少为`k`。 对于每个有效的分区，我们生成所有片段，对它们进行排序，并检查`k`-th 元素。 这在概念上是正确的，因为它直接遵循输出的定义。 

然而，分区的数量是指数级的`n / l`，因为每个段边界都是第一个可行切割之后的二元决策。 即使对于中等`n`，这立即爆炸。 此外，每次评估都需要排序`n / l`字符串并比较它们，这本身就很昂贵。 

关键的结构观察是我们实际上从来不需要完整的排序列表。 我们只关心候选作品是否可以成为`k`排序后的第 -th 。 这将问题转化为决策过程：修复候选子串并询问我们是否可以构造一个有效的分区，使得`k - 1`碎片严格小于它。 

一旦我们这样表述，问题在候选子串中就变得单调了。 如果一个子串作为答案是可行的，那么任何字典顺序较小的子串也是可行的，这使得可以对答案进行二分搜索。 为了评估可行性，我们贪婪地构建片段，同时跟踪有多少片段按字典顺序小于候选片段。 贪婪结构之所以有效，是因为较早采用较小的前缀只会增加小块的数量，而无助于减少小块的数量。 

最后一部分是有效计算子字符串比较。 我们不直接比较子字符串，而是使用滚动哈希或后缀数组技术，以便任何两个子字符串之间的字典顺序比较变得$O(1)$或者$O(\log n)$，在最坏的情况下保持整体解决方案的线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分割+排序| 指数| O(n) | 太慢了 |
 | 二分查找 + 贪婪 + 哈希/后缀比较 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 预先计算一个结构，允许在任意两个子串之间进行快速比较`s`。 这是必要的，这样我们就可以在不复制字符串的情况下评估字典顺序。 带有二进制提升的滚动哈希或后缀数组都可以工作。 
2. 对答案子串进行二分查找。 搜索空间是所有子串`s`。 我们使用预处理结构按字典顺序比较候选者。 
3. 对于固定候选子串`x`，我们通过贪婪扫描来检查可行性`s`并形成长度至少为`l`。 每次我们形成一个线段时，我们都会确定它是否严格小于`x`。 如果是，我们就增加一个计数器。 
4. 在扫描时，我们还确保剩余足够的字符以形成剩余的所需片段。 如果在任何时候我们无法保持可行性，我们就会提前停止。 
5.处理完整个字符串后，我们验证是否至少获得了`k - 1`段小于`x`并且至少`k`总体细分总数。 如果是这样，`x`是可行的。 
6.二分查找保持最大可行`x`，然后我们输出它。 

可行性检查中的贪婪决策至关重要。 当决定段边界时，扩展段只能使其按字典顺序变大，这减少了它被算作小于的机会`x`。 因此，为了最大化小段的数量，当当前段已经小于`x`。 

### 为什么它有效

 正确性取决于两个单调属性。 首先，候选子串的可行性在字典顺序方面是单调的：如果一个字符串`x`可以实现为第 k 个元素，那么也可以实现任何字典顺序较小的字符串，因为放宽目标只会更容易满足对有多少段更小的约束。 

其次，在可行性检查期间，贪婪的早期切割最大化了字典顺序小于的段的数量`x`。 任何延迟切割都只会扩展一个段，只能使其变大或相等，而永远不会将非小段变成小段。 这确保了贪婪模拟不会错过有效的构造。 

这些属性共同证明了对子字符串的二分搜索和每次检查的线性扫描。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n, l, k, s):
    if n < k * l:
        return None

    if k == 1:
        return s

    mod1 = 1000000007
    mod2 = 1000000009
    base = 91138233

    h1 = [0] * (n + 1)
    h2 = [0] * (n + 1)
    p1 = [1] * (n + 1)
    p2 = [1] * (n + 1)

    for i in range(n):
        v = ord(s[i]) - 96
        h1[i + 1] = (h1[i] * base + v) % mod1
        h2[i + 1] = (h2[i] * base + v) % mod2
        p1[i + 1] = (p1[i] * base) % mod1
        p2[i + 1] = (p2[i] * base) % mod2

    def get_hash(l, r):
        x1 = (h1[r] - h1[l] * p1[r - l]) % mod1
        x2 = (h2[r] - h2[l] * p2[r - l]) % mod2
        return (x1, x2)

    def leq(a, b):
        la, ra = a
        lb, rb = b
        if ra - la != rb - lb:
            return False
        return get_hash(la, ra) == get_hash(lb, rb)

    def smaller(a, b):
        la, ra = a
        lb, rb = b
        lo, hi = 0, min(ra - la, rb - lb)
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if get_hash(la, la + mid) == get_hash(lb, lb + mid):
                lo = mid
            else:
                hi = mid - 1
        if la + lo == ra:
            return True
        if lb + lo == rb:
            return False
        return s[la + lo] < s[lb + lo]

    def can(xl, xr):
        cnt = 0
        i = 0
        parts = 0
        while i < n:
            if parts >= k:
                break
            if n - i < l:
                return False
            j = i + l
            while j <= n:
                if smaller((i, j), (xl, xr)):
                    cnt += 1
                    parts += 1
                    i = j
                    break
                j += 1
            else:
                return False
        return parts >= k

    best = (0, 1)

    for i in range(n):
        for j in range(i + l, n + 1):
            if can(i, j):
                best = (i, j)

    if best == (0, 1):
        return None
    return s[best[0]:best[1]]

def main():
    totalQueryNum = int(input())
    for _ in range(totalQueryNum):
        n, l, k = map(int, input().split())
        s = input().strip()
        ans = solve_case(n, l, k, s)
        if ans is None:
            print("NO")
        else:
            print("YES")
            print(ans)

if __name__ == "__main__":
    main()
```该解决方案在字符串上构建滚动哈希，因此可以在不进行切片的情况下进行子字符串比较。 这`smaller`函数使用哈希匹配上的二进制提升按字典顺序比较两个子字符串，然后在第一次不匹配时回退到字符比较。 

这`can`函数模拟贪婪切割。 它重复地在当前索引处开始一个段并尝试扩展它，直到它变得小于候选子串。 一旦符合资格，它就会提交削减并继续。 这强制了我们最大化合格段数量的结构。 

外部搜索尝试候选子字符串。 在完全优化的实现中，这将被子串空间上的二分搜索所取代，而不是枚举所有对。

 ## 边缘情况

 一种边缘情况是当`n < k * l`。 例如，`n = 5, l = 2, k = 3`使得无法形成足够的段。 该算法在任何处理之前立即拒绝这一点，因为即使是最小的有效分区也无法满足要求。 

当字符串恒定时会出现另一种边缘情况，例如`"aaaaaa"`。 每个子字符串都是相同的，因此字典比较崩溃。 贪心检查器仍必须正确计算段数； 否则，它可能会错误地假设所有段都小于或大于候选段。 哈希比较确保显式处理相等性。 

第三种边缘情况是最佳答案位于字符串的边界，例如最​​后一个可能的子字符串。 二分搜索必须包括全范围候选者`[i, n]`，否则将错过以字符串边界结尾的有效答案。
