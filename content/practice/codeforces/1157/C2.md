 ## 解决方案
 ## 问题理解

 给定一个整数序列，我们必须通过重复获取最左边或最右边的元素来构造最长的可能严格递增序列。 每次我们获取一个数字时，它都会被附加到我们的增长序列中，并从原始序列中删除。 输出是双重的：该序列的长度和指示移动序列的字符串，其中“L”表示从左侧获取，“R”表示从右侧获取。 

这些约束允许序列最多包含 200,000 个元素。 由于 2 秒的限制，这排除了任何在指数时间内检查所有可能序列的解决方案。 我们需要一种在大致线性或线性算数时间内工作的方法。 每个元素都在 1 到 200,000 之间，因此我们可以直接存储和比较元素，而不必担心整数溢出。 

非明显的边缘情况包括具有重复数字的序列。 例如，序列`[2, 2, 2]`不能产生长于 1 的递增序列，并且移动必须仅选择第一个元素，然后停止。 另一个棘手的情况是最大的元素出现在两端，例如`[3, 1, 2, 3]`。 总是选择两端中较小的一个的天真贪婪方法可能会产生次优序列。 

## 方法

 蛮力方法很简单。 我们可以在每个步骤中递归地尝试这两个选项：如果它大于我们的增长序列中的最后一个元素，则取最左边或最右边的元素。 这正确地探索了所有可能的序列。 对于每个元素，最多有两个选择，大致导致`2^n`可能的序列。 和`n`达到20万，这是完全不可能的。 

最佳解决方案的关键见解来自于观察，即在任何时候，我们只需要考虑严格大于我们最后采用的元素的元素。 由于我们只能从末端开始，因此候选动作的顺序受到高度限制。 我们可以通过比较最左边和最右边的元素并始终选择扩展序列的较小元素来模拟贪婪方法。 如果两端都大于最后取出的元素，我们通过向前看直到一个数字停止严格增加条件来探索哪一侧可以产生更长的增加子序列。 

本质上，我们将问题简化为从每一端进行一系列严格递增的运行。 通过构建这些运行并比较它们的长度，我们总是做出最大化添加到序列中的元素数量的选择。 这避免了递归和指数探索，同时保持正确。

 | 具有前瞻的最优贪婪 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1.初始化两个指针，`l`在数组的开头和`r`最后还有一个变量`last`跟踪序列中的最后一个元素，从小于任何可能元素的值开始。 
2.初始化一个空字符串`moves`记录“L”和“R”移动的顺序。 
3.同时`l <= r`，我们检查两端的元素。 如果两者都`a[l]`和`a[r]`小于或等于`last`，我们停止，因为没有其他元素可以扩展序列。 
4. 如果只有两端之一严格大于`last`，获取该元素，更新`last`，移动指针，并将相应的移动附加到`moves`。 
5. 如果两端都严格大于`last`，构建两个候选序列：在序列保持严格递增的情况下重复向左移动，并以同样的方式分别向右移动。 比较它们的长度。 
6. 选择较长的候选序列，将相应的动作追加到`moves`， 更新`last`到最后添加的元素，并调整`l`或者`r`以反映所采用的所有元素。 
7. 重复此操作，直到无法获取任何元素。 

为什么有效：在每一步中，算法都会确保我们只添加比上一个更大的元素。 当两端都有效时，前瞻保证我们选择最大化连续递增元素数量的路径。 这个不变量——从不采用非递增元素并在不明确时选择最长的运行——确保整个序列严格递增并且尽可能长。

import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

l, r = 0, n - 1
last = 0
moves = []

while l <= r:
    left, right = a[l], a[r]
