 ## 解决方案
 ## 问题理解

 我们被要求探索通过重复应用特定变换函数生成的数字。 对于一个号码$x$，我们首先添加一个。 如果结果数字有尾随零，我们将它们全部删除，直到没有剩余。 这定义了函数$f(x)$。 一个数字$y$据说可以从$x$如果申请$f$零次或多次开始于$x$最终产生$y$。 

输入是单个整数$n$，输出是可到达的不同数字的计数$n$。 可联系的号码包括$n$本身以及通过重复应用获得的任何数字$f$。 

约束条件$1 \le n \le 10^9$意味着$n$适合标准整数类型，任何算法都应该避免迭代所有数字直到$n$因为这可能涉及多达十亿次操作。 理想情况下，解决方案在位数或运算数量上应该是线性或对数的。 

当数字以多个零结尾或略低于 10 的幂时，就会出现边缘情况。 例如，$n = 999$之后产生一个大的跳跃$f(999) = 1$。 如果实现不仔细处理这些跳转，天真地每次加 1 并删除零可能会导致循环或丢失数字。 另一种边缘情况是带有多个尾随零的数字，例如$n = 1000$，其中一个应用程序立即跳转到$1$。 

## 方法

 蛮力方法很简单：从$n$并反复申请$f$，将每个数字存储在一个集合中，直到有一个数字重复。 这保证了正确性，因为该过程最终必须达到先前看到的数字（所有数字都是正数，并且该函数减少尾随零，最终循环为更小的数字）。 在最坏的情况下，操作次数大约是重复归约过程中遇到的数字总数。 然而，对于$n = 10^9$，这可能接近数十亿步，这对于 1 秒的限制来说太慢了。 

关键的观察是，唯一可以从$n$是那些不同于$n$删除尾随零后以 1 为增量。 因此，我们可以跟踪生成的数字的计数$f$无需显式存储所有中间数字。 相反，我们可以重复计算$f(n)$直到它达到之前看到的值或减少到 0。生成的每个数字都是不同的，因为$f$严格增加数字，直到发生循环或减少。 

最佳方法使用应用变换的简单循环$f$直到达到之前看到的数字。 我们维护一个计数器，而不是显式存储每个数字。 由于每个应用程序都会减少尾随零的数量，因此序列无法重新访问比之前看到的任何数字都大的数字，这保证了以少量步骤终止。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 太慢了|
 | 最佳 | O(log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.将一个计数器初始化为0并设置当前数$x = n$。 计数器跟踪不同的可达号码的数量。 
2. 开始一个循环，直到$x$变为0。 
3.计数器加1进行计数$x$作为可达的。 
4. 计算$x = x + 1$。 通过重复除法删除所有尾随零$x$10 直到最后一位数字非零。 
5. 检查是否$x$已经到达了之前访问过的数字（在这种方法中，如果它减少到个位数，我们就知道剩下的数字都是个位数，所以我们可以在计数后退出）。 
6. 返回不同数字的总数。 

为什么它有效：不变的是每个应用程序$f$如果我们忽略尾随零，则会产生一个严格大于前一个数字的数字。 删除尾随零以防止序列中相同数字的重复表示。 最终，序列达到 10 以下的数字或已经出现过的数字，因此不会对任何数字进行两次计数，以确保正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def reachable_count(n):
    seen = set()
    x = n
    while x not in seen:
        seen.add(x)
        x += 1
        while x % 10 == 0:
            x //= 10
    return len(seen)

n = int(input())
print(reachable_count(n))
```该解决方案使用一组`seen`跟踪已访问过的数字，确保不计算重复项。 内部循环删除尾随零，实现该功能$f(x)$。 该算法终止是因为数字增加或减少到之前看到的数字。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(log n) | 每一步都会减少尾随零，最多是 n 中的位数。 每个数字最多被访问一次。 |
 | 空间| O(log n) | 该集合存储每个不同的数字，每个数字最多增加一个，与数字位数成比例。 |

 当n达到10^9时，步数最多是几十次迭代，完全在1秒之内。

 ## 边缘情况

 对于`n = 1000`,`f(1000) = 1001 -> 1001`然后删除零产生`1001`然后`1002`。 算法正确计数`1000, 1001, 1002, 1003`并终止。 为了`n = 999`,`f(999) = 1000 -> 1`然后继续通过`2..9`，各计数一次。 所有涉及尾随零或略低于十次方的数字的边缘情况都会得到正确处理，因为内部循环在继续之前会去除零。
