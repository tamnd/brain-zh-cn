 ## 解决方案
 ## 问题理解

 我们得到了大小的排列$n$。 将其视为一排卡片，其中每个值从 1 到$n$恰好出现一次。 每次移动时，我们只允许从当前行的最左端或最右端移除一张牌，并记录移除的值。 这将构建一系列选定值。 

我们的目标不是最大化总和或收集所有卡片，而是最大化有多少个选定的值按照我们选择的顺序形成严格递增的序列。 我们还需要输出一个有效的左/右决策序列，以达到这一最大长度。 

约束条件$n \le 2 \cdot 10^5$立即排除任何模拟所有可能的选秀序列的策略。 每个步骤都会分为两个选择，因此简单的搜索是指数级的。 即使是考虑所有子数组和最后选择的值的动态编程解决方案也会太大，除非仔细地将其简化为线性行为。 

当局部最优选择与全局结构发生冲突时，就会出现一个微妙的问题。 例如，总是选择两端中较小的一个似乎是合理的，因为它有助于维持递增顺序，但这可能会阻止访问隐藏在数组更深处的大递增尾部。 

另一种失败模式是仅基于当前目的的贪婪挑选。 在像这样的输入中$[1, 100, 2, 3, 4]$，总是首先选择较小的一端会导致取 1，然后被迫进入一个糟糕的延续，而稍微延迟的决定会产生更长的递增序列。 

因此，关键的困难在于我们需要一个在不断缩小的区间内全局一致的策略，并对输出序列进行单调约束。 

## 方法

 蛮力的观点很简单：在每个间隔$[l, r]$，尝试同时选择$a_l$和$a_r$如果它们大于最后选择的值，则递归并取最佳结果。 这探索了高度的二叉树$n$, 给予$O(2^n)$最坏情况下的状态。 即使使用记忆，对最后选择的值的依赖也会阻碍状态的有效压缩，因为“最后的值”可以在不同的路径上采取多种可能性。 

一旦我们注意到唯一相关的约束是最后选择的值，并且在每一步我们只将它与两个可用的端进行比较，结构就会简化。 该过程始终将左指针或右指针向内推进，因此剩余的结构始终是连续的子数组。 关键的观察是，除了确保下一个选择的值严格大于当前的最后一个值之外，我们不需要考虑未来的后果。 这使得贪婪模拟成为可能，我们总是在可能的情况下选择较小的有效端，因为它为未来的选择保留了更大的灵活性。 当只有一端有效时，我们就被迫接受它。 当两端都无效时，该过程停止。 

这将指数分支转变为收缩指针的单个线性扫描。

 ## 算法演练

 我们在当前区间维护两个指针，`l`和`r`，和一个变量`last`将最后选择的值存储在构造的序列中。 我们还建立了一系列动作。 

1. 初始化`l = 0`,`r = n - 1`，并设置`last = 0`因为所有值都是正数并且从 1 开始。 
2. 虽然`l <= r`，我们检查两位候选人`a[l]`和`a[r]`。 
3. 如果两者都`a[l]`和`a[r]`小于或等于`last`，我们停止，因为不存在有效的递增连续。 
4. 如果两者都大于`last`，我们选择两个值中较小的一个，并将相应的指针向内移动。 

选择较小的值会保留未来选择的较弱下限，这不会减少未来有效选择的数量。 
5. 如果只有其中一个大于`last`，我们必须取其中一个，因为另一个不能扩展递增序列。 
6. 在每个有效选择之后，附加`'L'`或者`'R'`到答案并更新`last`。 

### 为什么它有效

 在每一步中，算法都会维护剩余区间包含所有未使用的元素，并且到目前为止构建的序列是严格递增的。 当两端都有效时，选择较小的一端永远不会减少最佳可实现的长度，因为任何可以在较大的有效端之后开始的未来序列也可以在较小的有效端之后开始，但反之则不然。 这确保了我们永远不会“过度”并阻止未来潜在的选秀权。 由于每一步都会删除一个元素并且不再重新访问它，因此该过程会贪婪地构造一个最大长度的有效序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    l, r = 0, n - 1
    last = 0
    ans = []

    while l <= r:
        left = a[l]
        right = a[r]

        if left <= last and right <= last:
            break

        if left > last and right > last:
            if left < right:
                ans.append('L')
                last = left
                l += 1
            else:
                ans.append('R')
                last = right
                r -= 1
        elif left > last:
            ans.append('L')
            last = left
            l += 1
        else:
            ans.append('R')
            last = right
            r -= 1

    print(len(ans))
    print("".join(ans))

if __name__ == "__main__":
    solve()
```实现直接遵循两指针结构。 这`last`变量强制执行严格递增约束。 关键细节是严格对比`> last`，这确保了正确性，因为所有值都是不同的。 

当两端都有效时，比较`left < right`编码对较小候选者的贪婪偏好。 这是影响最优性的唯一决策点。 

循环终止条件`l <= r`确保每个元素最多被考虑一次。

 ## 边缘情况

 一个最小数组，例如$[1]$表明了算法初始化的正确性。 两端重合，因此唯一有效的移动是获取该元素，生成长度为 1 的序列。 

完全递减的数组，例如$[4,3,2,1]$证明当每一步只有一侧有效时，算法会退化为始终采用右端。 每个选择都是严格递增的，因为序列是从最大到最小消耗的。 

像这样的图案$[1,6,2,5,3,4]$强调了“选择较小的有效端”规则的必要性。 在多个步骤中，两端都是有效的，并且始终选择较小的，以保持未来的灵活性完好无损，从而允许提取完整的序列。
