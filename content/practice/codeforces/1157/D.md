 ## 解决方案
 ## 问题理解

 我们需要准确地分配`n`解决了跨越的问题`k`连续几天。 

让`a[i]`是当天解决的问题数`i`。 每天必须至少包含一个问题。 该序列必须严格递增，并且每天的值最多可以增长两倍：$$a_i < a_{i+1} \le 2a_i$$所有值的总和必须精确`n`。 

任务不是优化任何东西。 我们只需要构造一个有效的序列或者确定不存在这样的序列。 

这些限制是不寻常的。 天数可以大到`10^5`，而问题总数可能高达`10^9`。 任何试图搜索可能序列的算法都是没有希望的。 即使每天存储许多候选状态也太昂贵了。 我们需要一种直接的构造方法，该方法可以在大致线性的时间内运行`k`。 

第一个观察来自尽可能小的有效序列。 由于这些值必须是严格递增的正整数，因此最小序列为$$1,2,3,\ldots,k$$其总和是$$\frac{k(k+1)}2$$如果`n`小于该值，则不存在解，因为每个有效序列必须至少有那么多的总问题。 

当序列被迫太大时，就会出现第二种微妙的情况。 认为`k=3`和`n=100`。 从任意第一个值开始`x`，最大可能的序列大约是$$x,\ 2x,\ 4x$$总计`7x`。 增长限制限制了可以将总和装入序列中的量。 构造必须同时考虑增长下限和上限。 

考虑`n=5, k=3`。 

可能的最小总和是$$1+2+3=6$$所以正确答案是`NO`。 仅检查积极性的粗心实现可能会错误地输出`1 1 3`，但序列不是严格递增的。 

考虑`n=8, k=3`。 

一个有效的答案是$$1\ 2\ 5$$不，它无效，因为`5 > 2·2`。 当贪婪地将剩余问题扔到最后一天时，加倍限制很容易被忘记。 

考虑`n=26, k=6`。 

已使用的最小序列$$1+2+3+4+5+6 = 21$$只有 5 个额外问题需要分发。 该分布必须保持单调性和加倍约束。 只需将所有额外内容添加到最后一个元素即可创建$$1\ 2\ 3\ 4\ 5\ 11$$这违反了`11 ≤ 10`。 

这些例子表明，困难在于在维持所有局部约束的同时平衡额外的金额。 

## 方法

 蛮力方法会尝试生成递增序列，其总和为`n`并测试倍增条件。 即使对于中等值，这也会变得巨大。 具有固定和的递增整数序列的数量组合增长，并且`n`可以达到`10^9`。 穷举搜索是完全不可能的。 

关键的观察是每个有效序列都可以被视为基本序列$$x,\ x+1,\ x+2,\ \ldots,\ x+k-1$$加上一些在几天内分布的额外增量。 

如果第一个值固定为`x`，可达到的最小总和是$$kx + \frac{k(k-1)}2.$$这立即表明找到最大可能的起始值`x`其最低金额不超过`n`。 

为什么大的起始值有用？ 因为将每个元素加一会消耗`k`总和单位，同时自动保留所有约束。 我们希望吸收尽可能多的`n`在处理剩余的较小量之前尽可能以这种方式进行。 

修复后`x`，还有一些额外的金额$$r = n - \left(kx + \frac{k(k-1)}2\right).$$该序列开始为$$x,\ x+1,\ \ldots,\ x+k-1.$$现在我们分发`r`额外的单位。 加倍约束决定了每个位置可以增加多少。 从左到右处理，每个元素都可以增长，直到达到$$2a_{i-1}$$或仍需要的任何金额。 这种贪婪的分布首先最大化较早的元素，为后面的元素创造尽可能多的空间。 

如果处理完所有位置后余数变为零，则我们有一个有效的序列。 否则无法达到目标金额。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 最佳 | O(k) | O(k) | 已接受 |

 ## 算法演练

 1. 计算可能的最小总和：$$S_{\min}=\frac{k(k+1)}2$$如果`n < Smin`， 打印`NO`。 
2.找到最大的整数`x`这样$$kx+\frac{k(k-1)}2 \le n.$$这是$$x=\left\lfloor\frac{n-\frac{k(k-1)}2}{k}\right\rfloor.$$选择尽可能大的起始值可以吸收大部分总和，同时自动满足所有约束。 
3. 构建碱基序列$$a_i = x+i$$使用从零开始的索引。 
4. 计算剩余金额$$r = n-\sum a_i.$$5. 从末尾到开头处理位置。 

对于职位`i`，确定保持的最大增量$$a_i \le 2a_{i-1}.$$可用容量为$$2a_{i-1}-a_i.$$6. 添加$$\min(r,\text{capacity})$$到`a_i`，然后减去相同的数量`r`。 
7. 继续，直到处理完所有位置。 
8. 如果`r`仍为正值，打印`NO`。 否则打印`YES`和顺序。 

### 为什么它有效

 基本序列是具有第一个值的最小有效序列`x`。 任何具有相同第一个值的更大的有效序列只能通过添加非负增量来获得。 

当分配剩余金额时，增加后面的位置不会影响涉及前面位置的约束。 为每个位置提供尽可能多的位置可以最大化序列的未来容量。 如果这个贪婪过程不能吸收所有剩余单位，那么其他分配就不能吸收，因为每个头寸都已经达到了其最大合法值。 因此，当存在有效序列时，算法恰好成功。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    if n < k * (k + 1) // 2:
        print("NO")
        return

    x = (n - k * (k - 1) // 2) // k

    a = [x + i for i in range(k)]

    cur_sum = sum(a)
    rem = n - cur_sum

    for i in range(k - 1, 0, -1):
        cap = 2 * a[i - 1] - a[i]
        add = min(rem, cap)
        a[i] += add
        rem -= add

    if rem != 0:
        print("NO")
        return

    print("YES")
    print(*a)

solve()
```第一个检查处理基本的不可能性条件。 如果即使是严格递增的序列`1,2,...,k`超过`n`，不存在任何构造。 

价值`x`选择最大可行起始值。 这是将剩余调整减少到小于的关键想法`k`。 

该数组最初包含从以下位置开始的最小有效序列`x`。 其总和保证不超过`n`。 

其余部分从右向左分配。 对于每个位置，我们准确计算在加倍约束变得严格之前还剩下多少空间。 添加超过此数量将违反问题条件。 

最后的余数检查至关重要。 的一些值`n`即使不能被代表`n`超过最小总和。 在这些情况下，贪婪填充达到了所有容量，而一些剩余部分仍然存在，这证明是不可能的。 

所有算术都适合 64 位整数。 Python 整数会自动处理这个问题。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n, k = map(int, input().split())

    if n < k * (k + 1) // 2:
        return "NO\n"

    x = (n - k * (k - 1) // 2) // k

    a = [x + i for i in range(k)]
    rem = n - sum(a)

    for i in range(k - 1, 0, -1):
        cap = 2 * a[i - 1] - a[i]
        add = min(rem, cap)
        a[i] += add
        rem -= add

    if rem:
        return "NO\n"

    return "YES\n" + " ".join(map(str, a)) + "\n"

assert run("26 6\n").startswith("YES"), "sample"

assert run("1 1\n") == "YES\n1\n", "minimum input"

assert run("5 3\n") == "NO\n", "below minimum sum"

assert run("10 4\n") == "YES\n1 2 3 4\n", "exact minimum"

assert run("1000000000 1\n") == "YES\n1000000000\n", "largest n with k=1"

 ## 边缘情况

 考虑：```
5 3
```最小有效金额为$$1+2+3=6$$自从`5 < 6`，算法立即打印`NO`。 这可以防止满足总和但违反严格增加的结构。 

考虑：```
8 3
```算法构建`[1,2,3]`与余数`2`。 

最后一个位置有容量$$2\cdot2-3=1$$所以它变成了`4`，留下余数`1`。 

中间位置不能增加，因为它会破坏第一个元素的严格排序。 剩余部分幸存下来，因此算法输出`NO`。 

这正确地拒绝了诸如`1 2 5`，满足总和但违反加倍限制。 

考虑：```
100 3
```该算法从一个大的`x`，然后尝试分配剩余金额。 每个职位最终都会达到其最大合法价值。 如果仍有额外金额，算法将报告不可能。 这抓住了许多天真的贪婪解决方案忽视的上层增长限制。
