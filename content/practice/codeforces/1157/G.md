 ## 解决方案
 ## 问题理解

 我们被赋予了一个$n \times m$仅包含零和一的矩阵。 我们可以翻转任何行和任何列任意次数。 翻转意味着用相反的值替换该行或列中的每个值。 

应用所有选定的翻转后，按行优先顺序读取矩阵。 第一行先出现，然后是第二行，依此类推。 结果序列必须是非递减的。 因为每个值都是$0$或者$1$，非递减行优先序列意味着所有零出现在所有一之前。 

任务不是输出变换后的矩阵。 相反，我们必须输出哪些行和哪些列被翻转。 如果没有选择翻转可以使矩阵排序，我们打印`NO`。 

这些约束在一个维度上非常小，而在另一个维度上则相当大。 两个都$n$和$m$至多是$200$。 这立即排除了任何指数的情况$n+m$， 自从$2^{400}$是无望的。 另一方面，$200^3$甚至两秒内几百万次操作也是完全可以接受的。 

关键的难点在于行翻转和列翻转相互作用。 翻转一行会更改该行中的每个列条目。 翻转列会更改该列中的每个行条目。 对所有翻转组合进行简单搜索是不可能的。 

一些边缘情况很容易被错误处理。 

考虑一个已经排序的矩阵：```
1 3
0 0 1
```正确答案是：```
YES
0
000
```坚持执行至少一次翻转的解决方案将错误地拒绝这种情况。 

考虑：```
2 2
0 1
1 0
```任何行和列翻转序列都不能产生由一些零和一些 1 组成的行优先序列。 正确答案是：```
NO
```独立于列翻转来决定行翻转的贪婪策略可能会错误地认为存在解决方案。 

另一个微妙的情况是当从零到一的转换发生在行内时：```
2 3
0 1 1
1 1 1
```该矩阵已经排序。 零和一之间的边界不一定是在两行之间。 任何正确的表征都必须允许切割发生在一行内。 

## 方法

 最直接的强力方法是尝试行的每个子集和列的每个子集。 对于每个选择，构造结果矩阵并检查其行主序列是否已排序。 

有$2^n$行选择和$2^m$列选择。 即使是为了$n=m=20$，这变成了$2^{40}$，已经远远超出了实际的极限。 以实际极限为准$n=m=200$，穷举搜索是完全不可能的。 

突破来自于理解逐行读取时排序的二进制矩阵是什么样子。 

如果二进制序列由一些零和一些 1 组成，则该序列是非递减的。 当写回矩阵形式时，有一个唯一的“边界”将零区域与一区域分开。 

假设行优先顺序中的第一个出现在位置$(r,c)$。 然后：

 之前的所有行$r$必须仅包含零。 

之后的所有行$r$必须仅包含 。 

内排$r$, 之前的列$c$是来自的零和列$c$接下来是。 

这意味着每个排序的二进制矩阵完全由单个边界行和单个边界列确定。 

现在考虑翻转的效果。 让$R_i$表示是否行$i$被翻转并且$C_j$表示是否列$j$被翻转了。 最终值在$(i,j)$是$$a_{ij} \oplus R_i \oplus C_j.$$对于固定的边界位置，每个单元格都有一个所需的最终值，或者$0$或者$1$。 因此每个单元给出一个约束$$R_i \oplus C_j = a_{ij} \oplus b_{ij},$$在哪里$b_{ij}$是排序后的目标矩阵中的期望值。 

这是行变量和列变量的 XOR 方程组。 

二分异或系统可以通过固定一个变量并传播所有其他变量来解决。 由于只有$n+m \le 400$变量，检查一个边界很容易。 

存在多少个边界？ 转换可能发生在第一个单元格之前、最后一个单元格之后或任何矩阵位置。 将每个可能的边界行与每个可能的边界列一起尝试就足够了。 有$(n+1)(m+1)$最多的可能性$40401$。 

对于每个候选边界，我们求解一个最多涉及的系统$400$变量和$40000$限制。 由此产生的复杂性是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(2^{n+m} \cdot nm)$|$O(nm)$| 太慢了|
 | 最佳 |$O(n^2m^2)$|$O(nm)$| 已接受 |

 ## 算法演练

 ### 表征排序矩阵

 排序的行优先二元矩阵恰好具有从零到一的一次转换。 

选择边界行$r$和边界柱$c$。 

上面的行$r$完全为零。 

下面的行$r$完全是。 

排中$r$, 之前的列$c$是来自的零和列$c$接下来是。 

特殊情况自然会出现$r=0$,$r=n$,$c=0$， 或者$c=m$。 

### 求解固定边界

 1.构造期望值$b_{ij}$根据所选边界的每个单元格。 
2. 每个单元格产生一个方程$$R_i \oplus C_j = a_{ij} \oplus b_{ij}.$$3. 将行和列视为二分图的顶点。 

排$i$连接到列$j$带边缘标签$$a_{ij} \oplus b_{ij}.$$4. 修复一个变量，例如$R_0=0$。 
5. 通过二部图运行 BFS 或 DFS。 

如果$$R_i \oplus C_j = x$$并且一个端点是已知的，另一端点是唯一确定的。 
6. 如果我们遇到一个已经有值的顶点，请验证新隐含的值是否与现有值匹配。 
7. 矛盾意味着这个边界无法实现。 
8. 如果满足所有方程，则恢复所有行和列翻转值并输出。 
9. 如果没有边界有效，则输出`NO`。 

### 为什么它有效

 对于固定边界，每个有效解必须完全满足从所需目标矩阵导出的 XOR 方程。 这些方程完整地描述了行翻转和列翻转之间的关系。 

图传播分配的值与从起始顶点可到达的所有方程一致。 每当已分配的顶点收到不同的隐含值时，系统就会不一致，并且该边界不存在翻转配置。 

每个排序矩阵对应于某个边界位置。 由于算法会检查每个可能的边界，因此最终将检查任何有效的答案。 当找到一致的系统时，恢复的行和列翻转恰好产生目标排序矩阵，因此输出是正确的。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

n, m = map(int, input().split())
a = [list(map(int, input().split())) for _ in range(n)]

for r in range(n + 1):
    for c in range(m + 1):
        val = [-1] * (n + m)

        val[0] = 0
        q = deque([0])

        ok = True

        while q and ok:
            v = q.popleft()

            if v < n:
                i = v

                for j in range(m):
                    if i < r:
                        b = 0
                    elif i > r:
                        b = 1
                    else:
                        if r == n:
                            b = 0
                        elif c == 0:
                            b = 1
                        elif c == m:
                            b = 0
                        else:
                            b = 0 if j < c else 1

                    need = a[i][j] ^ b

                    to = n + j
                    want = val[v] ^ need

                    if val[to] == -1:
                        val[to] = want
                        q.append(to)
                    elif val[to] != want:
                        ok = False
                        break

            else:
                j = v - n

                for i in range(n):
                    if i < r:
                        b = 0
                    elif i > r:
                        b = 1
                    else:
                        if r == n:
                            b = 0
                        elif c == 0:
                            b = 1
                        elif c == m:
                            b = 0
                        else:
                            b = 0 if j < c else 1

                    need = a[i][j] ^ b

                    to = i
                    want = val[v] ^ need

                    if val[to] == -1:
                        val[to] = want
                        q.append(to)
                    elif val[to] != want:
                        ok = False
                        break

        if ok:
            rows = ''.join(str(val[i]) for i in range(n))
            cols = ''.join(str(val[n + j]) for j in range(m))

            print("YES")
            print(rows)
            print(cols)
            sys.exit()

print("NO")
```该解决方案迭代每个可能的边界。 对于每一个，它都会构建隐式目标矩阵，而不是显式存储它。 

数组`val`存储所有行和列变量的值。 指数`0..n-1`对应于行，而`n..n+m-1`对应于列。 

每个矩阵单元都给出一个 XOR 约束。 BFS 通过二部图传播分配。 每当顶点收到第二次分配时，代码就会立即检查一致性。 该检查是解决 XOR 系统的整个正确性条件。 

一个微妙的点是处理特殊边界。 什么时候`r == n`，整个矩阵必须为零。 什么时候`c == 0`，转换发生在行的第一列之前`r`，所以该行完全是 1。 什么时候`c == m`，转换发生在行的最后一列之后`r`，因此该行完全为零。 这些情况必须分开处理，以避免出现大错特错。 

另一个微妙的点是修复`R_0 = 0`不丢失任何解决方案。 XOR系统在同时翻转每个行变量和每个列变量的情况下是不变的。 固定一个变量只是从等价类中选择一个代表。

 ## 边缘情况

 考虑一个已经排序的矩阵：```
1 3
0 0 1
```该算法检查与第二个单元之后的转换精确对应的边界。 生成的 XOR 系统与所有翻转变量都等于 0 一致，从而产生正确的答案。 

考虑一个完全由 1 组成的矩阵：```
2 2
1 1
1 1
```有效边界位于第一个元素之前。 在实现中这对应于`c = 0`在第一行。 目标矩阵全为 1，给出一个一致的系统。 

考虑一个完全由零组成的矩阵：```
2 2
0 0
0 0
```有效边界位于最后一个元素之后。 案例`r = n`处理这种情况。 目标矩阵变为全零，算法立即找到解决方案。 

考虑：```
2 3
0 1 1
1 1 1
```转换发生在第一行内。 许多不正确的解决方案只考虑行之间的边界。 该算法显式枚举了边界行的每个列位置，因此它正确地发现了零行第一个元素之后的有效切割。
