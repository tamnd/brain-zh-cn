 ## 解决方案
 ## 问题理解

 我们从一个大小的数组开始$2^n$其中每个位置最初存储自己的索引，因此位置$i$保值$i$。 指数$i$也被解释为$n$位二进制数。 

唯一的非查询操作重复应用基于格雷码块的转换。 对于选定的级别$k$，我们查看仍然“足够小”的值，这意味着值小于$2^k$。 对于每个这样的值，我们将其替换为其下的图像$k$位格雷码排列$G_k$。 至少已经是的值$2^k$该步骤保持不变。 

每个 2 类操作都询问给定位置的当前值$p$，并且答案必须以二进制形式打印，不带前导零。 

重要的是更新不依赖于位置，只依赖于当前值。 该数组实际上是经过重复条件函数应用的值的多重集。 

这些限制改变了我们对暴力的看法。 数组长度为$2^n \le 1024$，所以直接对数组进行模拟并不大。 真正的困难在于每个 type-1 操作可能包含最多$2 \times 10^6$其列表中的级别，并且跨操作的总和以 5000 为界。这意味着任何解决方案都必须处理每个级别$k$本质上是在常数或对数时间内，并且每次更新时无法重新扫描整个数组。 

天真的解释会尝试通过重新计算每个步骤和每个元素的整个映射来应用每个格雷变换。 那立即就变成了$O(q \cdot 2^n \cdot m)$，即使很小，也太大了$n$， 自从$m$可以是巨大的。 

当思考“仅按顺序应用转换”时，会出现更微妙的失败案例。 两种不同的$k$价值观相互作用：后来的小$k$可以重新转换之前因较大而未受影响的值，但在以后的操作后可能会再次变小。 变换取决于当前值阈值，而不是原始位置。 

交互问题的一个最小例子是$k=2$之前应用过$k=1$。 第二个操作可能会或可能不会触及元素，具体取决于它们在早期格雷更新后是否保持在阈值以下。 基于位置的模拟错误地假设了更新的独立性。 

关键的见解是完全停止跟踪位置，而是跟踪每个值如何$x$进化。 由于规则仅取决于当前值，因此每个值的行为都是独立的。 我们只需要知道，对于每个初始值$x$，随着时间的推移，它应用了什么函数。 

## 方法

 蛮力方法按字面意思应用每个操作。 对于类型 1 操作，我们迭代所有$j < 2^{k_i}$并更新每个符合条件的数组单元格。 自从$n \le 10$，数组最多有1024个元素，所以这部分是可以管理的。 然而，问题是每次更新都需要检查并可能转换每个元素，并且可能有多达 5000 次操作，每次操作最多涉及 1024 个元素。 这给出了关于$5 \times 10^6$更新，这是边界，但仍然忽略了这样一个事实：每次更新本身都是不平凡的，因为格雷变换需要位操作和重复的应用程序逻辑。 

更重要的是，如果按位置实现，这种方法在概念上会失败，因为它会重复重新计算状态并失去值独立演化的结构。 

关键的观察是每个值$x$仅当其位于由 控制的范围内时才受影响$k$，并且在该范围内，变换恰好应用固定排列$G_k$。 由于格雷码是一个排列$[0, 2^k)$，每个操作都是二进制空间前缀上排列的条件组合。 

相反，我们可以为每个可能的值维护$x \in [0, 2^n)$，当前映射$f(x)$。 最初$f(x)=x$。 每个操作类型$k$更新全部$x < 2^k$通过申请$G_k$，这是该子集的已知排列。 所以我们在一个小域上组合部分排列。 

自从$n \le 10$，我们可以预先计算所有格雷码表$G_k$。 那么每次更新就变成了一小段大小的直接重新标记$2^k$。 该结构允许我们将每个操作视为对值空间前缀的直接转换，而不是对数组位置的直接转换。 

我们维持每个的当前值$x$，并仅将转换应用于受影响的范围。 由于操作总数很少，并且最大域为1024，所以这变得可行。

 | ---| ---| ---| ---|
 | 蛮力 |$O(q \cdot 2^n)$|$O(2^n)$| 交互太慢/混乱 |
 | 使用预先计算的灰色表进行值映射 |$O((\sum 2^{k_i}))$|$O(2^n)$| 已接受 |

 ## 算法演练

 1. 预先计算所有格雷码排列$G_k$为了$k \le n$。 每个$G_k$映射值$0 \ldots 2^k-1$使用标准递归结构进行格雷码排序。 这是至关重要的，因为每次更新都是这些固定排列的直接应用。 
2. 维护数组`val[x]`表示当前图像的初始值$x$。 最初`val[x] = x`。 
3. 对于具有序列的 type-1 操作$k_1, k_2, \dots, k_m$，处理每个$k_i$按顺序：

 1. 对于每一个$x < 2^{k_i}$， 更新`val[x] = G_{k_i}[val[x]]`仅当`val[x] < 2^{k_i}`。 
2. 范围之外的值保持不变，因为它们不受该转换级别的影响。 

该条件确保我们仅对活动子集应用排列，与问题定义完全匹配。 
4. 对于位置处的类型2查询$p$，将二进制输入转换为整数索引并输出二进制表示`val[p]`。 
5. 通过使用标准位格式转换整数，所有输出均以二进制打印，不带前导零。 

### 为什么它有效

 中心不变量是在任何时刻，`val[x]`正是应用所有可能影响价值的转换的结果$x$，按正确的顺序，并且不会在其有效域之外应用任何转换。 每个操作仅对值空间的固定前缀内的值进行排列，并且排列的组合是一致的。 由于每个转换都是其活动范围上的双射，因此不会丢失或错误地重复任何值，并且每个初始值的独立演化保证了查询的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
N = 1 << n

# precompute Gray code tables
gray = [[0] * (1 << k) for k in range(n + 1)]

for k in range(1, n + 1):
    size = 1 << k
    half = size >> 1
    prev = gray[k - 1]
    for i in range(half):
        gray[k][i] = prev[i]
        gray[k][size - 1 - i] = prev[i] + half

# value mapping
val = list(range(N))

out = []

for _ in range(q):
    tmp = input().split()
    op = int(tmp[0])

    if op == 1:
        m = int(tmp[1])
        ks = list(map(int, tmp[2:]))

        for k in ks:
            limit = 1 << k
            g = gray[k]
            for x in range(limit):
                if val[x] < limit:
                    val[x] = g[val[x]]

    else:
        p = tmp[1]
        p = int(p, 2)
        out.append(format(val[p], 'b'))

print("\n".join(out))
```该解决方案使用反射定义预先计算格雷排列，因此每个$G_k$可用于$O(2^k)$时间。 更新期间，仅前缀$0 \ldots 2^k - 1$被扫描，并且使用预先计算的表有条件地重新映射每个值。 

一个微妙的细节是以二进制形式解析查询索引。 由于输入给出$p$作为二进制字符串，直接转换它可以避免前导零的错误，并确保正确索引到值数组中。 

另一个微妙之处是条件更新`val[x] < limit`。 如果没有它，以后的转换将错误地重新映射已经转义的值，从而违反了问题的约束，即仅当前较小的值受到影响。

 ## 边缘情况

 一种极端情况是当多个小$k$操作在不同的顺序中重叠。 例如，申请$k=2$然后$k=1$更改哪些值仍然适合以后的转换。 条件检查`val[x] < 2^k`确保一旦某个值超出范围，就不会被错误地重新处理。 

另一种边缘情况是重复应用相同的内容$k$。 由于格雷码是一种排列，应用它两次不会恢复同一性，除非排列是对合的，而一般情况下并不是这样。 该算法自然地处理这个问题，因为它始终应用当前映射而不是假设可逆性。 

最后一个边缘情况是查询格式化。 由于输入给出的二进制字符串没有前导零，因此需要直接整数解析； 将它们视为十进制会默默地为除微不足道的情况之外的所有情况产生错误的索引。
