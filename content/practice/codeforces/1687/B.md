 ## 解决方案
 ## 问题理解

 我们有一个铁路网络，包括`n`车站和`m`双向轨道，每个轨道都有正长度。 网络可能未完全连接，并且同一对车站之间可以有多个轨道。 每个轨道可以是功能性的，也可以是非功能性的，我们可以通过发送长度为二进制的字符串来模拟轨道的任何子集`m`在哪里`1`表示该轨道处于活动状态并且`0`表示不活动。 模拟器返回激活轨道的“全跨越森林”的最大容量。 从概念上讲，全生成森林是激活子集的每个连接组件内的最大生成树。 

我们的目标是确定**当所有轨道都正常运行时铁路系统的最小容量**，即整个图上完整跨越森林的最小总和。 

这里的关键限制是`n`最多 200 并且`m`最多 500，这使我们能够执行最多`O(m^2)`考虑到 2m 模拟器查询的限制，操作舒适。 

非明显的边缘情况包括断开的图，其中一些轨道是桥梁、车站之间的多条轨道以及长度相等的轨道。 粗心的方法，例如贪婪地求和所有轨道长度或忽略轨道顺序，将过量计算容量或错过正确的最小值。 

## 方法

 一种简单的方法是模拟轨迹的每个可能的子集，以找到给出最小全范围森林的子集。 这显然是不可行的，因为有`2^m`子集，甚至对于`m = 20`这是超过一百万个查询。 由于子集的指数数量，暴力破解会失败。 

关键的观察结果是，模拟器本质上充当黑匣子，用于评估任何边缘子集上**最大跨越森林**的权重。 整个图的最小全生成森林对应于每个组件的**最小生成树**。 我们可以使用模拟器贪婪地重建MST：从没有轨道开始，迭代添加容量增加最少的轨道。 这是有效的，因为按照权重递增的顺序向森林添加边模仿了 Kruskal 算法。 我们保持连通性，并且仅在需要时添加可增加总容量的轨道。 

这将问题简化为“贪婪边缘选择”过程，其中我们按长度对边缘进行排序并将它们一一相加，查询模拟器以检查每条边缘是否对最小容量有贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^m) | O(2^m) | O(米) | 太慢了|
 | 贪心MST模拟| O(m log m) | O(米) | 已接受 |

 ## 算法演练

 1.读取站数`n`和轨道`m`，以及边列表及其端点和长度。 
2. 按边的长度升序对边进行排序。 排序确保我们按照从最小到最大的顺序处理边，这反映了 MST 的 Kruskal 算法的逻辑。 
3. 初始化查询字符串`s`长度`m`全为零，代表一片空旷的森林。 
4. 初始化变量`current_capacity`通过查询没有活动轨道的模拟器。 这给出了空系统的基本容量，该容量为零。 
5. 迭代已排序的边。 对于每条边：

 a. 暂时激活查询字符串中的边。 

b. 使用更新后的字符串查询模拟器。 

c. 如果返回的容量与`current_capacity`，将边保留在活动集中并更新`current_capacity`。 否则，停用边缘并继续。 
6. 处理完所有边缘后，`current_capacity`对应于系统的最小容量。 输出这个值。 

这种贪婪方法背后的原因是，按长度升序添加边可确保我们永远不会包含不必要的大边，从而导致容量膨胀。 通过检查模拟器，我们只包含实际有助于连接组件的边，就像 Kruskal 的 MST 算法所做的那样，但使​​用模拟器而不是显式联合查找。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def query(s):
    print(f"? {''.join(s)}")
    sys.stdout.flush()
    return int(input())

def main():
    n, m = map(int, input().split())
    edges = []
    for i in range(m):
        u, v, l = map(int, input().split())
        edges.append((l, i, u-1, v-1))  # 0-indexed
    
    edges.sort()  # sort by length
    
    s = ['0'] * m
    current_capacity = 0
    
    for l, idx, u, v in edges:
        s[idx] = '1'
        new_capacity = query(s)
        if new_capacity > current_capacity:
            current_capacity = new_capacity
        else:
            s[idx] = '0'
    
    print(f"! {current_capacity}")
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```此实现仔细跟踪每次边缘添加后的当前容量。 它确保仅当边缘可能对 MST 做出贡献时才查询模拟器，从而防止不必要的查询。 通过将输入站转换为 0 索引，并在每次查询后刷新标准输出，可以避免差一错误，从而保证交互器立即接收输入。 

## 工作示例

 **示例1**

 输入边沿：```
edges = [(0,1,5), (1,2,9), (2,3,7), (3,4,1)]
```按长度排序：`(3,4,1), (0,1,5), (2,3,7), (1,2,9)`| 步骤| 边缘添加 | 查询结果 | 当前容量|
 | --- | --- | --- | --- |
 | 0 | 无 | 0 | 0 |
 | 1 | (3,4,1) | (3,4,1) | 1 | 1 |
 | 2 | (0,1,5) | (0,1,5) | 6 | 6 |
 | 3 | (2,3,7) | 13 | 13 |
 | 4 | (1,2,9) | (1,2,9) | 22 | 22 22 | 22

 最终容量为`22`。 每条边仅在增加总跨越森林权重时才做出贡献。 

**示例 2（断开连接）**

 输入边沿：```
edges = [(0,1,2), (2,3,3)]
```排序：`(0,1,2), (2,3,3)`| 步骤| 边缘添加 | 查询结果 | 当前容量|

 | 0 | 无 | 0 | 0 |
 | 1 | (0,1,2) | (0,1,2) | 2 | 2 |
 | 2 | (2,3,3) | 5 | 5 |

 该算法通过分别向每个组件添加边来正确处理断开连接的组件。

 ## 边缘情况

 对于断开连接的图，该算法可以独立地正确查询每个组件。 对于等长的多条边，排序可以保持顺序稳定，并且模拟器仅选择那些增加容量的边。 最小尺寸图（2 个节点，1 个边）的处理很简单。 对于带有桥的图，该算法仅包括那些有助于连接组件的边，确保不会出现过度计数。
