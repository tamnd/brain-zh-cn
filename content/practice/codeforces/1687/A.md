 ## 解决方案
 ## 问题理解

 我们被要求计算玛丽莎在一维森林中在有限的分钟内可以收集的蘑菇的最大数量。 沿轴的每个位置都以给定数量的蘑菇开始，每分钟，玛丽莎最多向左或向右移动一步，收集当前位置上的所有蘑菇，然后每个位置都会产生一个新蘑菇。 她无法在第 0 分钟收集蘑菇，因此第一次收集发生在第 1 分钟。每个测试用例的输出是一个整数，表示玛丽莎可以收集的最大蘑菇`k`分钟。 

输入限制清楚地表明，必须仔细考虑朴素的方法。 最多可以有`2 × 10^5`所有测试用例中的位置，以及`k`可以达到`10^9`。 这排除了任何单独模拟每分钟的方法，因为直接模拟可能需要最多`10^14`运营。 初始计数和每分钟的增长都是大整数，最多`10^9`，因此我们必须注意具有固定大小整数的语言中的整数溢出，尽管 Python 本身可以处理大整数。 

边缘情况包括只有一个位置或`k`相对于而言非常大`n`。 例如，如果单个位置有 999999 个蘑菇，`k=2`，玛丽莎在第一步中收集了 999999，如果她再次访问，增长会增加两个蘑菇，产生一个简单的算术序列。 幼稚的运动模拟可能会错误地尝试一分钟一分钟地迭代，或者错误地假设她可以移动到森林之外。 

## 方法

 蛮力方法很简单：尝试每个起始位置，模拟每一分钟`k`步骤，并跟踪收集的蘑菇总数。 这是正确的，因为它完全枚举了所有可能性，但对于大的情况却失败了`k`因为这需要`O(n * k)`每个测试用例的操作，当`k`可以达到`10^9`。 

关键的观察结果是，各个职位的增长是线性且均匀的。 如果玛丽莎按照初始计数的降序加上她到达蘑菇的分钟数的顺序从位置收集蘑菇，则她可以使总和最大化。 这导致了一种贪婪的方法：按初始蘑菇数量对位置进行排序，模拟每分钟收集最大的剩余可用蘑菇，并相应地增加生长计数器。 由于她每分钟最多可以移动一步，因此她从当前位置可以到达的最远距离受到剩余分钟的限制，但问题的结构允许我们以递减的权重来处理排序后的值，这大大减少了从`k`迭代到排序位置的简单循环。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n * k) | O(n) | 太慢了|
 | 贪心排序| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，请阅读`n`和`k`和最初的蘑菇阵列`a`。`n`是职位数量，`k`是分钟数。 
2. 对数组进行排序`a`按降序排列。 这确保我们首先考虑蘑菇最多的位置，从而最大化收集。 
3. 初始化变量`total`为零。 这将积累收集到的蘑菇。 
4. 迭代已排序的数组。 对于索引处的每个位置`i`（从 0 开始），将有效集合计算为`a[i] + min(k, i)`。 这里，`i`表示如果我们总是从最佳可用位置贪婪地移动，则到达该位置所需的移动次数。 
5.将此值添加到`total`。 停止迭代时`i`达到`k`，因为玛丽莎赚的钱不能超过`k`移动。 
6. 输出`total`作为测试用例的答案。 

工作原理：贪婪算法保持了这样的不变性：在每分钟，Marisa 从对蘑菇生长贡献最大的位置收集数据。 按初始计数排序可确保我们不会错过更大的集合，并将迭代限制为`k`遵守行动限制。 这`min(k, i)`确保我们分配的增长量不会超过 Marisa 过去的分钟数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def max_mushrooms():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort(reverse=True)
        total = 0
        for i in range(min(n, k)):
            total += a[i] + i
        print(total)

if __name__ == "__main__":
    max_mushrooms()
```代码首先读取测试用例的数量。 对于每个测试用例，它读取森林大小`n`以及可用分钟数`k`，以及蘑菇数量数组。 排序`a`按降序排列可确保我们始终首先考虑最佳位置。 循环最多迭代`min(n, k)`次，对应于给定时间内 Marisa 可以到达的最大位置数，并使用以下公式添加增长贡献`i`。 印刷`total`输出该测试用例的最大蘑菇数。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) | O(n log n) | 排序占主导地位； 随后的循环是 O(min(n, k)) ，最多是 O(n) |
 | 空间| O(n) | 存储数组和排序后的副本 |

 该算法很容易满足约束条件。 排序`2 × 10^5`elements在2秒内可行，额外的循环是线性的。 内存使用量远低于 256 MB 限制。

 ## 边缘情况

 对于具有很多分钟的单个位置，例如输入`1 10 100`，该算法正确地将初始值加上上限的增长相加`k`。 为最大`k`情景，即`min(n, k)`确保我们不会尝试访问不存在的数组元素。 对于所有相等的值，顺序并不重要，算法仍然通过应用来计算正确的总数
