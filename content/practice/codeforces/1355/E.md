 ## 解决方案

 ## 问题理解

 我们有一排柱子，每个柱子都有一个初始高度。 目标是改变这些高度，使每根柱子最终都达到相同的高度。 我们可以添加砖块、移除砖块或在柱子之间移动砖块，每种砖块都有不同的成本。 

关键的决定是我们不要求匹配固定的目标高度。 相反，我们必须自己选择最终的共同高度，并且该选择决定了我们需要多少种类型的操作。 对于任何选定的高度，其上方的柱子会贡献多余的砖块，而其下方的柱子则需要不足的砖块。 多余的部分可以通过移动或移除来廉价地处理，而赤字则可以通过移动或添加来满足。 

输入大小将我们推向每个测试用例至多 O(N log V) 或 O(N) 的算法，因为 N 可以达到 100000 并且高度可达 10^9。 如果每个评估都是线性的并且范围很大，则独立尝试每个可能的目标高度的幼稚策略会太慢。 

在决定操作时会出现一个微妙的点：移动一块砖有时比移除加添加更便宜，但并非总是如此。 这会创建一个依赖于将 M 与 A + R 进行比较的成本结构。如果忽略此比较，解决方案可能会过度使用移动或从不使用它们，两者都会导致不正确的结果。 

当移动比单独操作便宜得多时，就会发生典型的失败情况。 例如，如果 A = 5，R = 5，M = 1，那么移动应该主导添加和删除，但始终独立处理盈余和赤字的幼稚分割策略会付出过高的代价。 

当移动比删除和添加的组合成本更高时，就会出现另一种边缘情况。 如果 A = 1、R = 1、M = 100，则根本不应该使用任何移动，并且任何贪婪地移动匹配盈余-赤字对的算法都将产生次优结果。 

## 方法

 蛮力的想法很简单：固定目标高度 H，计算高于 H 的总过剩量和低于 H 的总赤字量，然后计算使用可用操作平衡它们的成本。 尝试 0 和最大高度之间的所有可能的 H 给出正确性，因为最佳解决方案必须对应于某个整数高度。 

然而，高度范围高达 10^9，使得直接迭代变得不可能。 即使我们限制为唯一的高度，仍然有最多 10^5 个值，并且每个候选值的重新计算成本为 O(N)，在最坏的情况下为 O(N^2)。 

关键的观察结果是 H 上的成本函数在结构上是凸状的。 随着 H 的增加，盈余减少，而赤字单调增加。 这使我们能够在线性时间内评估任何固定 H 的成本，然后使用整数域上的三元搜索来搜索最小值。 更重要的是，我们可以在对高度进行排序后使用前缀和有效地计算每个评估。 

排序后，我们可以使用二分搜索快速计算出在任何候选高度之上和之下有多少块砖。 这将每次成本评估减少到 O(log N)，并且完整搜索变为 O(N log N + log V log N)。 在实践中，更标准和最优的解决方案完全避免三元搜索，并直接使用前缀和和对排序高度的单次扫描来计算成本，从断点导出最佳候选高度。 

最重要的结构性见解是，对于固定的目标高度，问题分解为两部分：供给过剩和需求不足。 唯一的复杂性是通过移动或通过删除+添加对将过剩转化为赤字是否更便宜。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解所有 H | O(NV) | O(1) | O(1) | 太慢了|
 | 排序+前缀+线性候选| O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 我们首先对支柱高度进行排序，以便我们可以有效地推断出有多少支柱高于和低于候选目标。 

1. 按非降序对高度数组进行排序。 这允许我们将任何候选高度视为数组中的分割点，其中左边的所有内容都在下面，右边的所有内容都在上面。 
2. 计算高度的前缀和。 这使我们能够快速计算任何线段的总高度，这对于计算赤字和盈余是必要的，而无需重复重新计算总和。 
3. 考虑一个候选最终高度 H。对于固定的 H，找到高度至少为 H 的第一个索引。左边的所有内容都是赤字，右边的所有内容都是盈余。 
4. 将赤字计算为将所有低于 H 的元素提高到 H 所需的总量。这是 H 乘以较低元素的计数减去它们的总和。 这代表我们必须获得的砖块。 
5. 计算剩余量，即我们可以从 H 以上元素中移除的总量。这是 H 以上元素之和减去 H 乘以这些元素的计数。 这代表可用的砖块。 
6. 决定如何解决盈余和赤字。 如果移动一块砖比单独移除和添加砖块更便宜，那么首先使用移动直到盈余和赤字最小。 否则，使用删除和添加操作独立处理盈余和赤字。 
7. 高度 H 的总成本变为移动匹配盈余-赤字对的成本加上单独处理的剩余不匹配盈余和赤字。 
8. 评估所有相关候选高度的成本，特别是所有不同的输入高度加上潜在的边界极值，并取最小值。 

为什么有效：对于任何固定的目标高度，最优策略总是贪婪地将盈余和赤字配对，因为每次移动都会直接同时减少这两个数量。 任何剩余的盈余必须被消除，任何剩余的赤字必须被添加。 由于每块操作的成本是线性的并且是独立的，因此对于固定的 H，分解为匹配对和残差是全局最优的。最终答案是通过优化盈余和赤字组成发生变化的所有可能的结构断点来获得的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, A, R, M = map(int, input().split())
    h = list(map(int, input().split()))
    
    h.sort()
    
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + h[i]
    
    # helper to compute cost for target height H
    def cost(H):
        import bisect
        k = bisect.bisect_left(h, H)
        
        low_cnt = k
        high_cnt = n - k
        
        low_sum = pref[k]
        high_sum = pref[n] - pref[k]
        
        deficit = H * low_cnt - low_sum
        surplus = high_sum - H * high_cnt
        
        move_pairs = min(deficit, surplus)
        
        if M < A + R:
            return move_pairs * M + (deficit - move_pairs) * A + (surplus - move_pairs) * R
        else:
            return deficit * A + surplus * R
    
    # candidates: all unique heights
    candidates = set(h)
    
    ans = float('inf')
    for H in candidates:
        ans = min(ans, cost(H))
    
    print(ans)

if __name__ == "__main__":
    solve()
```该代码对高度进行排序并构建前缀和，以便可以通过二分搜索在对数时间内回答每个成本查询。 功能`cost(H)`计算相对于 H 必须添加和移除多少块砖块，然后决定通过移动进行配对操作是否有益。 最后的循环仅评估等于现有支柱高度的候选高度，这已经足够了，因为成本函数仅在这些点改变斜率。 

一个微妙的实现细节是比较`M < A + R`。 这决定了将移除加添加转换为移动是否有利。 如果搬家更便宜，我们会尽可能多地配对剩余和赤字砖块； 否则，我们完全忽略移动。

 ## 边缘情况

 当所有柱子都具有相同高度时，就会出现一种边缘情况。 在这种情况下，对于等于该高度的 H，赤字和盈余都为零，并且该算法正确地产生零成本，因为不需要任何操作。 

另一种情况是移动是最好的选择。 如果 A 和 R 较大但 M 较小，则算法在应用任何剩余操作之前将所有盈余和赤字配对。 对于像这样的输入`1 100 100 1`有高度`[0, 10]`，赤字和盈余在 H = 5 附近都等于 5，并且该算法使用总共花费 5 的 5 次移动，正确地避免了昂贵的添加/删除操作。 

第三种情况是移动没有用的时候。 如果 M >= A + R，则算法从不使用移动，而是独立支付添加和删除费用。 为了`[1, 1000, 1000, 1000]`这仍然产生零成本，并且对于倾斜阵列，它可以避免任何不正确的配对，否则会增加成本。
