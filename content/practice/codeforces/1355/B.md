 ## 解决方案
 ## 问题理解

 我们得到了一个探险家列表，每个探险家都与一个数字相关联$e_i$这代表他们加入的任何团体中必须有多少人。 如果探索者有价值$e$，那么他们只愿意参加规模至少为$e$。 任务是将部分或所有探索者划分为尽可能多的有效组，同时尊重每个组内每个成员的约束。 

每个测试用例都是独立的。 对于每一个，我们只需要输出我们可以形成的最大组数，而不是分组本身。 

约束足够大，任何解决方案都必须接近线性或$n \log n$每个测试用例。 由于所有测试用例的元素总数受以下限制$3 \cdot 10^5$，对每个测试用例进行排序然后处理一次的解决方案就足够了，而任何重复尝试以天真的方式贪婪地构建组的方法在最坏的情况下都会退化为二次行为。 

当试图将探索者逐一分配而不进行排序时，就会出现一种微妙的失败模式。 例如，如果我们尽早看到一个大需求并将其单独放置，我们稍后可能会发现它可以与其他需求组合在一起形成多个有效组。 另一种失败模式是尝试按到达顺序贪婪地形成组，而不考虑小$e_i$值应该用于有效地“填充”组，否则会很大$e_i$价值观可能变得无法定位。 

## 方法

 蛮力策略试图逐步构建群体。 我们反复挑选剩余探索者的子集，测试它是否可以形成有效的组，如果可以则将其删除。 这是正确的，因为它直接遵循约束定义。 问题是每次尝试都可能扫描剩余阵列的大部分以验证可行性，在最坏的情况下，这会导致大约$O(n^2)$当反复重新考虑探索者时每个测试用例的行为。 

关键的结构观察是，一个群体的条件仅取决于其规模，而不取决于身份。 一旦我们按探索者的身份对他们进行排序$e_i$，我们可以贪婪地建立群体，同时保持我们积累的候选人数量。 每当可用探索者的累积数量达到或超过当前元素的要求时，我们就可以最终确定一个组并重置计数器。 这是有效的，因为延迟一个组只会增加可用成员的数量，而不会降低可行性。 

这将问题简化为对排序数组的单次传递，我们在其中跟踪当前正在考虑为潜在组的元素数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(n)$| 太慢了 |
 | 排序+贪婪扫描|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 首先我们对数组进行排序$e_i$按非递减顺序。 排序确保我们始终首先尝试满足最小的要求，这是至关重要的，因为它们最容易放置并充当形成有效组的填充物。 

然后，我们扫描排序后的数组，同时维护一个计数器，该计数器表示我们已经向当前组积累了多少个探索者。 每次我们包含一个探险家时，我们都会将该计数器增加一。 

当计数器等于当前探索者的要求时，我们关闭一个组。 此时，我们将计数器重置为零，因为这些资源管理器现在已被分配并且无法重复使用。 

此检查以相等（而不是大于）的方式进行的原因是，一旦我们有足够的成员来满足当前池中最弱的要求，超出该点的任何额外积累最好用于立即开始形成下一个组。 

### 为什么它有效

 排序后，数组的任意一个前缀都包含了剩余元素中可能要求最小的元素。 当我们在最早的有效点形成一个组时，我们确保不会过早浪费具有较大需求的元素，并为后续步骤保留灵活性。 每个组对应一个最大分段，其中累积计数恰好满足最后包含元素的阈值，确保没有组违反大小限制并且不会跳过有效分组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        e = list(map(int, input().split()))
        e.sort()

        cnt = 0
        groups = 0

        for x in e:
            cnt += 1
            if cnt >= x:
                groups += 1
                cnt = 0

        print(groups)

if __name__ == "__main__":
    solve()
```该解决方案首先对需求进行排序，以便我们首先处理更容易的约束。 变量`cnt`跟踪当前形成的组的大小。 每次我们添加一个资源管理器时，我们都会通过比较来检查当前组是否有效`cnt`以目前的要求`x`。 一旦生效，我们立即完成分组并重置。 

一个常见的错误是等到`cnt == x`而不是`cnt >= x`。 当出现多个小值时，仅相等会失败，因为组可能比预期更早生效，并且延迟检查会导致不必要的大组，从而减少形成的总数。

该轨迹表明，当组已经可行时，该算法不会延迟该组，从而确保最大分区。

这证实了排序后的贪婪累积正确地平衡了小需求和大需求。

 ## 边缘情况

 最小单元素情况确保具有要求 1 的探索者始终单独形成一个组，因为计数器立即满足条件。 

所有值都等于的情况$n$确保只能形成一组，因为没有任何前缀达到大小$n$在消耗所有元素之前，确认算法在要求较高时不会过度计数。 

严格递增的序列可确保早期的小值正确充当填充符，并且大值不会错误地强制过早分组。 排序的贪婪传递自然会延迟关闭，直到存在足够的积累，从而保持正确性。
