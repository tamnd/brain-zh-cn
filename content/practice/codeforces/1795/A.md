 ## 解决方案
 ## 问题理解

 我们有两堆垂直的彩色块。 每个堆栈从下到上被描述为仅包含两个符号的字符串：B 代表蓝色，R 代表红色。 唯一允许的移动是取出一个堆栈的顶部块并将其放置在另一堆栈的顶部，重复任意次数。 

目标是确定我们是否可以重新排列两个堆栈之间的块，以便在最终配置中，两个堆栈都不包含列中任何位置的两个相同颜色的相邻块。 换句话说，每个堆栈必须严格从下到上交替颜色。 

关键的观察结果是，移动不会改变每个堆栈中组合的块的多重集，但它们确实允许随着时间的推移任意重新分配顶部元素。 由于我们可以重复传输顶部块，因此只要我们遵守堆栈排序约束，两个堆栈的任何交错都是可以实现的。 

限制非常小：每个塔最多有 20 个块，最多有 1000 个测试用例。 这立即排除了对试图模拟所有移动序列的状态的任何繁重搜索。 即使在单一情况下状态空间很小，移动序列上的分支仍然可能会组合爆炸。 

一个天真的想法是将其视为状态上的 BFS，其中每个状态都是一对堆栈，并且每次移动都会传输一个顶部元素。 这已经随着深度呈指数级增长，因为每次移动都会显着增加可达配置的数量。 

假设我们可以自由地排列塔之间的所有块，就会产生一个更微妙的问题。 这并不是直接正确的，因为堆栈在内部保留顺序。 例如，忽略堆栈约束的贪婪重新分配可能会产生实际无法达到的配置。 

一个误导性的情况是两个堆栈都包含交替模式但“未对齐”：

 输入：```
1
3 3
RBR
BRB
```人们很容易说这总是有效的，但根据移动顺序，如果忽略顺序约束，人们可能会假设不正确的可行性。 正确的答案是肯定的，但天真的“仅计数”推理在更结构化的情况下仍然会失败。 

真正的困难不是计数或排列，而是我们是否可以将最终的交替结构分离到两个堆栈上，同时尊重所有块都来自单个有序的传输过程。 

## 方法

 强力模拟将对两个堆栈进行显式建模并尝试所有可能的移动序列。 每次移动都会选择两个堆栈中的一个，并将其顶部的块移动到另一个。 即使进行了修剪，状态数量也会快速增长，因为每个块都可以在堆栈之间多次振荡，从而导致指数分支因子。 

关键的简化来自于认识到我们实际上并不关心移动执行的顺序，只关心最终的安排。 由于任何块最终都可以通过一系列合法的顶部传输序列移动到任一堆栈，因此唯一真正的限制是我们是否可以将每个块分配给两个交替序列之一，以便每个结果堆栈的颜色交替。 

这将问题简化为检查我们是否可以将块的多重集分割成两个交替序列。 每个序列本身必须有效：一旦起始颜色固定，堆栈的其余部分就会被强制。 

因此，对于每个可能的分配，我们只需要确保没有堆栈以两个连续的相同颜色结束。 因为除了总计数之外，两个堆栈都是独立的，所以我们只需要检查是否存在遵守交替约束的有效分割。 

这导致了直接的建设性检查：尝试每个堆栈的起始颜色的两种可能性，并验证每个堆栈中的 B 和 R 计数是否可以排列成交替模式而不发生冲突。

 ## 算法演练

 1. 计算两个堆栈中 B 和 R 块的总数。 这些总数是固定的，代表我们可以分配的所有可用资源。 
2. 请注意，有效的最终配置必须由两个交替序列组成。 一旦其起始颜色和长度固定，每个序列就完全确定。 
3.对于固定的堆栈长度，交替序列有一个精确的要求：如果以B开头，则B必须占据奇数位置； 如果以R开头，则R占据奇数位置。 这会在长度和所需计数之间创建直接映射。 
4. 尝试两个堆栈的起始颜色的所有组合。 对于每个选择，使用 B 和 R 的全局计数来模拟是否可以满足两个堆栈的交替要求。 
5. 对于每个作业，计算每个堆栈需要多少个 B 和 R。 如果所需总数与可用计数完全匹配，则该配置是可行的。 
6. 如果任何分配有效，则输出 YES。 否则输出NO。 

### 为什么它有效

 任何有效的最终状态完全取决于我们如何将块划分为两个交替序列。 由于移动允许在不改变区块身份的情况下进行任意重新分配，因此可行性仅取决于 B 和 R 的全球供应是否能够满足两种交替的需求模式。 交替结构消除了每个堆栈内的所有自由度，将问题转化为对恒定数量奇偶校验配置的有限检查。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def required_counts(length, start):
    # start = 'B' or 'R'
    # returns (need_B, need_R)
    if start == 'B':
        need_B = (length + 1) // 2
        need_R = length // 2
    else:
        need_R = (length + 1) // 2
        need_B = length // 2
    return need_B, need_R

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    s1 = input().strip()
    s2 = input().strip()

    total_B = s1.count('B') + s2.count('B')
    total_R = n + m - total_B

    ok = False

    for start1 in ['B', 'R']:
        for start2 in ['B', 'R']:
            b1, r1 = required_counts(n, start1)
            b2, r2 = required_counts(m, start2)

            if b1 + b2 == total_B and r1 + r2 == total_R:
                ok = True

    print("YES" if ok else "NO")
```该实现首先计算颜色的全局库存。 然后，它列举了为两个交替堆栈选择起始颜色的四种可能方法。 对于每种配置，它会准确计算每个堆栈在完美交替时需要多少 B 和 R。 

微妙之处在于我们从不模拟动作。 该操作模型保证了区块的完全可转移性，因此可行性仅取决于所需总数是否与可用总数匹配。 

辅助函数对交替堆栈的确定性结构进行编码：一旦起始颜色固定，则强制每隔一个位置，因此计数是唯一确定的。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    import sys as _sys

    input = _sys.stdin.readline

    t = int(input())
    out = []

    def solve():
        n, m = map(int, input().split())
        s1 = input().strip()
        s2 = input().strip()

        total_B = s1.count('B') + s2.count('B')
        total_R = n + m - total_B

        def req(length, start):
            if start == 'B':
                return (length + 1) // 2, length // 2
            else:
                return length // 2, (length + 1) // 2

        for a in 'BR':
            for b in 'BR':

                b2, r2 = req(m, b)
                if b1 + b2 == total_B and r1 + r2 == total_R:
                    ok = True

        out.append("YES" if ok else "NO")

    for _ in range(t):
        solve()

    return "\n".join(out)

 ## 边缘情况

 当一个堆栈已经交替而另一个堆栈尚未交替时，就会出现极端情况。 该算法仍然有效，因为它从不依赖于初始结构，只依赖于总计数。 例如：```
2 2
BR
RR
```总 B = 1，总 R = 3。长度 2 和 2 的任何交替分配都需要至少一个堆栈中有 2 个 B 或 2 个 R，而这是无法满足的，因此输出为 NO。 

另一种边缘情况是两个堆栈都是统一的，例如所有 B。即使移动可以重新分配块，也无法进行交替配置，因为任何长度大于 1 的交替堆栈都需要两种颜色，从而立即导致计数检查失败。
