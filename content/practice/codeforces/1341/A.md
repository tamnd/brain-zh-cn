 ## 解决方案
 ## 问题理解

 我们给出了关于一袋米粒的几个独立场景。 在每种情况下，都存在两层不确定性：每粒谷物的重量和所有谷物的总重量。 

已知每种谷物都有一个整数重量，位于某个平均值周围的对称区间内。 另外，所有谷物的总重量也被限制在另一个对称区间内。 问题是是否存在对所有颗粒的整数权重分配，使得每个颗粒都遵循其自己的允许范围，并且所有颗粒的总和落在允许的总范围内。 

我们没有被要求构建权重，只是为了确定这种配置在逻辑上是否可行。 

每个测试用例的约束很小，最多有 1000 个粒度和最多 1000 个测试用例。 这立即表明任何解决方案都必须是每个测试用例的恒定时间，因为即使每个用例的线性扫描也已经达到大约 10^6 次操作，这仍然没问题，但是任何涉及分布的嵌套推理的操作都是不必要的并且是过度的。 

只考虑平均值会产生一个微妙的陷阱。 一个天真的想法是将平均粒重范围与总区间隐含的平均值进行比较。 这是不正确的，因为总约束是在总和上，而不是在每粒平均值上，并且极值配置很重要。 

另一个潜在的错误是独立处理边界而不进行缩放。 总范围与 n 成比例，但粗心的实现可能会忘记乘以每晶界，从而导致不正确的可行性检查。 

## 方法

 强力解释是在允许的范围内尝试所有可能的谷物重量分配，并检查任何分配是否在所需的间隔内产生总和。 即使对于单个测试用例，每个颗粒也最多有大约 2001 个可能值的范围，因此组合的数量约为$(2001)^n$，即使对于非常小的 n 也是完全不可行的。 问题的结构表明我们不需要检查个人作业。 

关键的观察是我们不关心权重的确切分布，只关心总和的可能范围。 由于每个颗粒是独立的，并且贡献相加，所以当每个颗粒取其最小值时，达到最小可能的总和，当每个颗粒取其最大值时，达到最大可能的总和。 这将整个问题变成了检查两个区间是否重叠：可实现的总区间和所需的总区间。 

一旦我们计算出可实现的总和范围，可行性就减少到检查这两个区间是否相交。

 ## 算法演练

 对于每个测试用例，我们都会执行少量的确定性步骤。 

1. 计算单粒谷物的最小可能重量：$a - b$。 这是每粒的最小允许值。 
2. 计算单粒谷物的最大可能重量：$a + b$。 这是每粒谷物的最大允许值。 
3. 两者相乘$n$获得最小和最大可能的总重量：$S_{\min} = n(a - b)$和$S_{\max} = n(a + b)$。 这一步是合理的，因为每个颗粒都是独立贡献的，我们可以选择每个颗粒的极端值来推动总和。 
4. 根据输入计算允许的总重量区间：$[c - d, c + d]$。 
5. 检查这两个区间是否相交。 具体来说，我们验证最大可实现总和至少是允许的最小总和，并且最小可实现总和最多是允许的最大总和。 
6. 如果两个条件都成立，则输出“Yes”； 否则输出“否”。 

### 为什么它有效

 独立有界变量的和总是通过将每个变量推向其自身的极值来达到其极值。 选择所有最小值的任何偏差都会增加总和，而选择所有最大值的任何偏差都会减少总和，因此没有中间配置可以将可达区间扩展到超出$[n(a-b), n(a+b)]$。 因此，问题准确地归结为检查该可达间隔是否与所需间隔重叠，这对于可行性来说既是必要的也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, a, b, c, d = map(int, input().split())
    
    min_sum = n * (a - b)
    max_sum = n * (a + b)
    
    low = c - d
    high = c + d
    
    if max_sum >= low and min_sum <= high:
        print("Yes")
    else:
        print("No")
```实现直接遵循导出的区间推理。 关键细节是将每粒间隔的两个端点正确缩放 n。 一个常见的错误是比较$a-b$和$a+b$直接与总边界相乘而不相乘，这会忽略聚合。 

重叠条件是对称的：任一端点都可以验证可行性，但必须检查两者以确保间隔相交，而不是一个端点严格包含另一个端点。 

## 工作示例

 我们跟踪两个示例案例以了解区间比较的行为方式。 

### 示例 1

 输入：`7 20 3 101 18`| 步骤| 最小颗粒 | 最大颗粒度| 最小总和| 最大总和| 总间隔| 结果 |
 | ---| ---| ---| ---| ---| ---| ---|
 | 计算| 17 | 17 23 | 23 119 | 119 161 | 161 [83, 119] | 是的 |

 可实现的总和范围是 [119, 161]，而所需的范围是 [83, 119]。 间隔在 119 处相交，因此在所有晶粒均取最小值的边界情况下可行性完全成立。 

### 示例 2

 输入：`11 11 10 234 2`| 步骤| 最小颗粒 | 最大颗粒度| 最小总和| 最大总和| 总间隔| 结果 |
 | ---| ---| ---| ---| ---| ---| ---|
 | 计算| 1 | 21 | 21 11 | 11 231 | 231 [232, 236] | 没有 |

 这里最大可能的总和是 231，但所需的间隔从 232 开始。即使是最有利的配置也无法达到所需的总和。 

这些例子表明边界接触是有效的，严格分离会导致失败。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        n, a, b, c, d = map(int, input().split())
        min_sum = n * (a - b)
        max_sum = n * (a + b)
        low = c - d
        high = c + d
        out.append("Yes" if (max_sum >= low and min_sum <= high) else "No")
    return "\n".join(out)

 ## 边缘情况

 当间隔恰好接触到一点时，就会出现一种重要的边缘情况。 例如，如果可实现的最大总和等于所需的最小总和，则正确答案仍然是“是”。 该算法处理这个问题是因为条件使用非严格不等式，确保边界可行性被接受。 

另一种情况是当 n 等于 1 时。问题简化为检查两个间隔是否直接重叠，并且缩放步骤仍然可以正常工作，因为乘以 1 会保留间隔。 

第三种情况是 b 等于 0 或 d 等于 0 时。这会将一个或两个区间折叠为单个点。 该算法仍然有效，因为交集检查自然地处理简并区间而无需特殊的大小写。
