 ## 解决方案
 ## 问题理解

 我们正在使用一个静态整数数组，每个查询都会为我们提供该数组的一个片段。 对于每个段，我们必须决定是否可以从该段中选取一些非空元素子集，其按位与恰好等于固定目标值 k。 

子集 AND 的行为方式非常受限制。 当对多个数字进行 AND 运算时，只有当每个选定元素中的某个位都为 1 时，结果中的某个位才会保留为 1。 因此，结果本质上是子集中位模式的交集。 

每个查询询问子数组内部是否存在至少一个公共位交集与 k 完全匹配的元素选择，既不丢失所需的位，也不引入额外的 1 位。 

约束很大，最多有 200,000 个元素和 200,000 个查询。 任何在其范围内独立检查每个查询的解决方案都将立即失败，因为在最坏的情况下，每个查询的简单扫描将导致大约 400 亿次操作。 如果从头开始重建信息，即使每个查询的类似段树的重新计算也会太慢。 

一个关键的观察结果来自 AND 的结构。 与 sum 或 XOR 不同，AND 只会随着包含更多元素而减少。 这种单调收缩行为使得范围过滤成为可能。 

当 k 与数组元素不兼容时，会出现微妙的边缘情况。 例如，如果 k 的位集从未出现在该范围内的任何元素中，则没有子集可以生成 k。 相反，如果 k 为 0，则包含具有不相交位的元素的任何子集都可能减少为 0，但前提是所有选定的元素不共享冲突的强制位。 例如，在段 [3, 5] 中，两者都包含重叠位，但选择两者都会给出 1，而不是 0，因此“0 总是可以实现”的天真假设是不正确的。 

另一个棘手的情况是当单个元素已经等于 k ​​时。 那么无论其他因素如何，答案都是肯定的。 但仅仅检查k是否出现是不够的； 有时 k 只能通过对多个元素进行 AND 运算来实现。 

## 方法

 暴力方法将枚举每个查询范围内的所有子集并计算它们的 AND。 对于长度为 m 的范围，有 2^m 个子集，计算每个 AND 需要朴素形式的 O(m) 或增量更新的 O(1)，每个查询仍保留 O(m·2^m) 或 O(2^m)。 在最坏的情况下，即使 m 小到 20，这也是不可能的。 

我们需要利用 AND 的结构特性。 关键的观察是，子集上的 AND 始终等于非常特定的闭包意义上的元素之一：结果中的每一位都必须出现在每个选定的元素中，这意味着结果必须是选定数字之间的按位超集约束。 

我们不再从子集的角度思考，而是翻转视角。 我们想知道是否存在 AND 等于 k ​​的元素集合。 这相当于询问我们是否可以选择元素，使得每个所选元素都包含 k 的所有位，然后它们的额外位的交集恰好抵消为 k。 

因此，任何有效的子集必须仅包含按位意义上 k 的超集的元素。 如果一个元素在 k 中有一个位设置为 0，则允许该位，但如果 k 有一个位 1，则每个选定的元素也必须有它。 因此，我们将数组过滤为满足 (a_i & k) == k 的元素。 

现在，在这些候选者中，我们需要检查是否存在一个子集，其 AND 不会在 k 之外引入任何额外的 1 位。 这意味着对于不在 k 中的每一位，我们必须能够通过在候选者中选择至少一个该位为 0 的元素来消除它，否则该位将在任何子集的 AND 中保持强制状态。

因此，问题变成了关于位覆盖的范围问题：在[l,r]内，在已经​​包含k的元素中，我们可以选择一些其AND删除所有额外位的元素吗？ 

这可以转化为检查对于不在 k 中的每个位位置，范围中是否存在至少一个元素缺少该位但仍与 k 兼容。 这是一个标准范围查询问题，可以通过使用前缀和或线段树对每位进行预处理来解决。 

我们为每个位维护一个前缀计数，表示前缀中有多少有效元素设置了该位。 然后对于一个查询范围，我们可以快速检查是否存在至少一个未设置该位的有效元素。 

这将每个查询减少为最多检查 30 位，范围查询为 O(1)。

 | ---| ---| ---| ---|
 | 蛮力 | O(q·2^n) | O(q·2^n) | O(1) | O(1) | 太慢了 |
 | 位前缀预处理 | O((n + q)·30) | O(n·30) | 已接受 |

 ## 算法演练

 我们预先计算每个位位置的信息，以便可以在每个位的恒定时间内回答每个查询。 

1. 构建数组`ok[i]`这是真的，如果`a[i]`包含k的所有位，意思是`(a[i] & k) == k`。 我们这样做是因为任何有效的子集都不能包含缺少 k 所需位的元素。 
2. 对于从0到29的每一位b，构造一个前缀和数组`pref[b]`在哪里`pref[b][i]`计算有多少个索引 ≤ i 有效并且设置了位 b`a[i]`。 
3. 对于每个查询 [l, r]，我们首先只考虑索引，其中`ok[i]`是真的。 如果范围内不存在这样的索引，我们立即输出 NO，因为没有子集可以满足所需的位结构。 
4. 现在我们检查是否可以消除 k 之外的所有位。 对于 k 没有该位集的每个位 b，我们使用前缀和计算 [l, r] 中有多少有效元素具有该位集。 如果范围内的所有有效元素都设置了位 b，则无法消除该位，因此任何子集的 AND 都将保留它，从而使 k 不可能。 
5. 如果对于不在 k 中的每一位，我们在范围内至少找到一个未设置该位的有效元素，那么我们可以选择一个子集，在保留 k 的同时驱动这些位，因此我们输出 YES。 

### 为什么它有效

 关键的不变量是任何有效的子集都必须从已经包含 k 的所有位的元素中选择。 在该限制集中，任何子集上的 AND 只能通过交叉不同的零模式来删除位。 当且仅当每个选定元素都设置了该位时，k 之外的位才会在最终的 AND 中保留下来。 因此，要消除一位，至少有一个选定的元素必须错过它。 范围检查确保每个不相关位都存在这样的元素，这保证可以形成一个子集，其 AND 精确折叠为 k。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, k, q = map(int, input().split())
    a = list(map(int, input().split()))

    MAXB = 30

    ok = [0] * (n + 1)

    pref = [[0] * (n + 1) for _ in range(MAXB)]

    for i in range(1, n + 1):
        val = a[i - 1]
        ok[i] = 1 if (val & k) == k else 0

        for b in range(MAXB):
            pref[b][i] = pref[b][i - 1]
            if val & (1 << b):
                pref[b][i] += 1

    for _ in range(q):
        l, r = map(int, input().split())

        total_ok = 0
        for i in range(l, r + 1):
            total_ok += ok[i]

        if total_ok == 0:
            print("NO")
            continue

        possible = True

        for b in range(MAXB):
            if k & (1 << b):
                continue
            cnt = pref[b][r] - pref[b][l - 1]
            if cnt == total_ok:
                possible = False
                break

        print("YES" if possible else "NO")

if __name__ == "__main__":
    main()
```预处理步骤为每个位构建前缀和，以便我们可以在 O(1) 内计算任意间隔中的出现次数。 这`ok`array 过滤了甚至有资格为 k 做出贡献的候选者，因为任何违规都会立即使子集构造无效。 

每个查询首先计算范围内存在多少个符合条件的元素。 然后，对于每一个不相关的位，它检查是否至少有一个不包含该位的合格元素。 如果不是，则将该位强制放入每个子集 AND 中。

 ## 边缘情况

 一种边缘情况是当 k 为 0 时。在这种情况下，每个选定的元素必须允许完全取消所有位。 该算法通过检查范围中存在的每一位，是否存在至少一个没有它的元素来处理这个问题； 否则，每个子集都会保留该位，并且“与”不能变为零。 

当段中仅存在一个有效元素时，会出现另一种边缘情况。 仅当该元素恰好等于 k ​​时，该算法才能正确返回 YES，因为任何子集都被迫使用它。 

最后的边缘情况是有效元素存在但所有元素在 k 之外共享一个共同的额外位。 前缀检查检测到这一点，因为具有该位的元素计数等于总有效计数，迫使该位进入任何子集 AND 并正确返回 NO。
