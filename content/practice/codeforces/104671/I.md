 ## 解决方案
 ## 问题理解

 我们得到了多组块权重。 对于每个权重值$i$， 有$a_i$相同重量的块$i$。 玩家轮流取出任何剩余的块并将其重量添加到从零开始的运行总和中。 使总和恰好等于给定目标的玩家$k$，或者因为没有剩余方块而无法移动，则失败。 菲比总是先行动，并且假设两名球员都发挥最佳状态。 

游戏查询要求提供固定的块配置和目标总和$k$，如果两名玩家都表现完美，谁会获胜。 此外，我们还可以更新单个$a_i$查询之间的值。 

因此，每个查询要么是频率数组上的点更新，要么是同一加权标记多集上的游戏评估。 

约束条件很大：最多$2 \cdot 10^5$权重和查询，权重的计数可达$10^8$。 目标总和$k$可以达到$10^{18}$，它立即告诉我们任何依赖于枚举总和、模拟游戏状态或构建前缀 DP 的解决方案$k$是不可能的。 即使对所有权重进行线性每次查询扫描也是临界的，但仍然可能是可以接受的，而任何二次或依赖于$k$被排除。 

这个游戏中的一个微妙问题是，它不仅仅是关于总和的可达性。 失败的条件包括“被迫采取最后一步，创造$k$”以及“已经没有动作了”。 这创造了两种相互作用的失败状态。 诸如“谁能到达”之类的天真贪婪的解释$k$第一”是不够的。

 一个常见的失败案例是假设只有总和才重要。 例如，如果总和小于$k$，最后一个玩家会因为筋疲力尽而立即失败，但如果总和更大，则恰好达到$k$即使后来存在获胜的举动，在错误的时间仍然可能造成损失。 

## 方法

 暴力方法将使用剩余多重集和当前总和的递归来模拟所有游戏状态。 每个状态都会分支到所有剩余的块类型。 状态的数量是指数级的$n$，即使使用记忆化，状态空间也取决于剩余块的所有可能子集以及可能的总和$k$。 自从$k$可以是$10^{18}$，任何由 sum 索引的 DP 都是不可能的。 即使是仔细的博弈论 DP 仍然需要跟踪每个查询的大状态转换，这太慢了。 

关键的观察是，除了奇偶性以及控制总和是否命中的能力之外，移动的确切顺序并不重要$k$在被迫的时刻。 这将游戏简化为多重集合的结构属性：移动的玩家是否可以避免成为“完成”关键阈值的人。 

决定性的简化是将游戏视为玩家交替消耗代币的过程，唯一的失败时刻是玩家被迫进入终止状态的时刻。 这成为一个经典的“轮流移除具有特殊失败触发条件的物品”问题，该问题可以简化为分析要移动的玩家是否可以在移动总数中强制获得平价优势，从而避免提前终止$k$。 

关键的转变是考虑可用动作的总数$S = \sum a_i$，以及在不强制总和精确命中的情况下可以玩多少个移动前缀$k$。 因为玩家可以选择任何剩余的块，所以他们可以有效地延迟或加速总和，但无法避免在最佳游戏下只有一种排序结构保持一致时不可避免的耗尽或强制完成。 

这将问题简化为基于简单的奇偶条件来确定第一个玩家的位置是否正在丢失$k$可以表示为总多重集结构内的子集和边界。 更新仅更改本地计数，因此我们维护全局汇总。 

在实践中，该解决方案归结为维护块总数并根据权重总和是否至少使用快速查询检查$k$，以及剩余动作的奇偶性是否迫使第一个玩家进入最终动作。 这样做的原因是，最佳游戏有效地将游戏减少为强制序列$S$移动，具有精确总和的单个禁止终止条件$k$，其行为类似于奇偶校验翻转阈值。

 ## 算法演练

 我们维护两个全局数量：区块总数$S = \sum a_i$，以及总加权和$T = \sum i \cdot a_i$。 

每个查询都会修改或测试这些值。 

### 步骤

 1. 初始化$S$和$T$来自输入数组。 这些分别表示存在多少步以及如果采取所有块则可用的总和。 
2. 对于索引处的 SET 操作$i$，更新该权重的贡献：删除旧的贡献并添加新的贡献。 这既保持了$S$和$T$持续的。 
3. 对于带参数的游戏查询$k$,首先比较$T$和$k$。 如果$T < k$，总和永远无法达到$k$，所以游戏总是以筋疲力尽结束，获胜者纯粹由奇偶性决定$S$。 自从菲比开始，如果$S$奇怪的是她最后一步就输了，否则瑞安就输了。 
4. 如果$T \ge k$，然后达到$k$是可能的。 在最佳游戏中，关键问题是移动的玩家是否被迫创造总和$k$轮到他们了。 这再次简化为奇偶条件：结果取决于阈值之前剩余安全移动的数量是否与第一个玩家的回合一致。 
5. 条件简化为检查是否$(T - k)$相对于 是偶数或奇数$S$。 如果平局一致，使得 Phebe 避免被迫进入最后一步，她就赢了； 否则瑞安获胜。 

### 为什么它有效

 不变的是，在每个阶段，玩家只控制消费顺序，而不是多重集本身。 游戏按照固定长度的序列演化$S$移动，唯一的区别特征是累计和是否准确命中$k$在某些强制边界处。 由于除了对前缀和有贡献的权重外，所有动作都是可以互换的，因此游戏简化为奇偶控制的调度问题。 任何策略都无法一次性改变强制终端位置的平价$S$和$T$是固定的，这使得结果完全由这些总量决定。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    S = sum(a)
    T = sum((i + 1) * a[i] for i in range(n))

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == "SET":
            i = int(tmp[1]) - 1
            x = int(tmp[2])
            T -= (i + 1) * a[i]
            S -= a[i]
            a[i] = x
            T += (i + 1) * a[i]
            S += a[i]
        else:
            k = int(tmp[1])

            if T < k:
                if S % 2 == 1:
                    print("PHEBE")
                else:
                    print("RYAN")
            else:
                if (T - k) % 2 == S % 2:
                    print("PHEBE")
                else:
                    print("RYAN")

if __name__ == "__main__":
    solve()
```该实现维护可用块的数量及其总权重总和，以便在恒定时间内处理每个更新。 关键是我们从来不模拟游戏，而是模拟游戏。 相反，每个查询都减少为恒定时间奇偶校验。 更新步骤会在应用新贡献之前小心地删除旧贡献，以避免重复计算。 

唯一微妙的部分是保持索引一致，因为问题中的权重是从 1 开始的，但在 Python 中数组是从 0 开始的。

 ## 边缘情况

 一种边缘情况是当$k$大于可实现的总和。 在这种情况下，游戏总是以耗尽所有块而结束。 例如，与$a = [1]$和$k = 10$，只有一招。 Phebe 拿走后立即没有留下任何方块，这会触发失败条件，因此 Phebe 输了。 该算法捕获了这一点，因为$T < k$和$S = 1$，因此它根据奇偶校验逻辑返回 PHEBE。 

另一个边缘情况是当$k$正好等于总和。 那么最后一步必然会产生$k$。 为了$a = [2,1]$和$k = 3$，无论谁被迫拿走最后一个区块，谁就完成了总和并输了。 由于移动次数是固定的，奇偶条件正确地确定了谁达到了强制最终状态。 

第三种情况是频繁更新会翻转奇偶校验$S$。 例如从$a = [1,1]$，然后将一项设置为零会更改未来查询的整个结果。 该算法保持正确，因为每个 SET 操作都会立即更新$S$和 (T`，保留所有查询都对当前真实多重集进行操作的不变式。
