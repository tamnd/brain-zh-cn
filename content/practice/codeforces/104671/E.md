 ## 解决方案
 ## 问题理解

 我们得到一排卡片，每张卡片要么面朝上，要么面朝下。 移动包括选择卡片当前面朝上的位置，然后将所有卡片从该位置翻转到行的末尾，包括所选卡片本身。 翻转可切换每个卡的状态。 

只要存在至少一个有效的移动，该过程就会继续。 仅当所选位置当前包含面朝上的牌时，移动才有效。 目标不是选择特定策略，而是确定在配置达到没有面朝上牌的状态之前可以执行的最大可能移动次数。 

这些约束允许字符串长度最大为 200000，这会立即排除每次操作以线性时间重复扫描和翻转段的任何模拟。 尝试直接模拟每次翻转的简单方法每次操作最多需要 O(n) 次工作，在最坏的情况下可能有 O(n) 次操作，导致 O(n^2)，这太慢了。 

当推理贪婪地模拟从左到右的翻转时，会出现一个微妙的问题。 翻转对后缀的影响是全局的，因此早期的决定会影响所有未来的状态。 这使得局部贪婪选择变得不可靠，除非我们找到压缩过程的全局不变量。 

一个小的说明性边缘情况是一个像这样的字符串`OXO`。 如果我们尝试总是选择最左边的`O`，国家以创造和破坏非本地机会的方式演变。 任何模拟方法都必须仔细考虑影响后缀的翻转奇偶性，否则会误算操作。 

## 方法

 蛮力的想法很简单。 我们维护当前字符串并重复从左到右扫描以查找任何面朝上的卡片。 一旦我们找到一个索引 i 和`O`，我们将所有字符从 i 翻转到 n。 每次翻转的时间复杂度为 O(n)，扫描的时间复杂度也为 O(n)，因此每次操作的成本为 O(n)。 在最坏的情况下，我们可能会在没有任何操作之前执行 O(n) 操作`O`仍然存在，导致时间复杂度为 O(n^2)，这对于 2e5 来说太慢了。 

关键的洞察力来自于重新定义行动的实际作用。 每次操作相当于选择一个位置i，当前有效状态为`O`，并切换后缀。 我们可以观察到，重要的是每个位置受到后缀翻转影响的次数，而不是在每次操作后跟踪整个字符串。 

如果我们从左到右处理，同时保持应用于后缀的翻转的运行奇偶性，我们可以确定当前字符是否有效`O`或者`X`随时。 每次我们遇到有效的`O`，我们被迫以最大操作顺序从该位置开始执行翻转，因为否则`O`将永远保留并允许稍后进行另一次有效操作。 这将问题转化为计算我们被迫开始后缀翻转的次数。 

因此，我们不是模拟字符串，而是跟踪一个奇偶校验变量，该变量表示当前前缀是否已被翻转偶数次或奇数次，并贪婪地决定何时必须发生翻转。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 前缀奇偶贪婪| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从左到右扫描字符串，同时维护一个变量`flip`表示当前位置是否已被之前的操作翻转了奇数次。 

1. 初始化`flip = 0`和`ans = 0`。 变量`flip`跟踪当前字符是否相对于其原始值反转。 
2. 对于从 0 到 n-1 的每个索引 i，计算该卡的有效值。 如果原来的角色是`O`，那么它是面朝上的，当`flip = 0`并面朝下时`flip = 1`。 如果是的话`X`，解释相反。 
3. 如果位置 i 处的有效值朝上，则可以从 i 处开始进行有效操作。 在最大操作序列中，我们必须立即执行它，因为延迟它不会产生任何好处，只会推迟强制后缀翻转。 
4. 当我们在 i 处执行操作时，我们增加答案并切换`flip`。 这表示所有未来的立场现在都相对于之前的解释颠倒了。 
5. 继续扫描直至结束。 我们触发翻转的总次数就是答案。 

关键思想是，每个强制操作都会消耗当前最早可用的正面朝上的牌，并将其效果传播到后缀，这正是通过切换单个奇偶校验状态来捕获的。 

### 为什么它有效

 在任何时候，唯一重要的决定是当前位置是否有效地面朝上。 如果是，则不翻转它就不能成为最大长度序列的一部分，因为它保留了可以立即执行的操作。 立即执行，统一变换后缀状态，不会减少以后强制操作的次数； 它只会改变他们。 这在最大操作和我们遇到新有效的次数之间创建了一对一的对应关系`O`在奇偶校验翻转下从左到右扫描期间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    flip = 0
    ans = 0

    for ch in s:
        if ch == 'O':
            cur = flip ^ 0
        else:
            cur = flip ^ 1

        if cur == 1:  # effective face-up
            ans += 1
            flip ^= 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现依赖于将原始字符串编码为二进制解释，其中`O`是 0 并且`X`为1，然后跟踪是否flips invert意思。 XOR 运算捕获后缀切换效果而不修改字符串。 

最微妙的部分是解读`cur`。 标准化后我们将面朝上视为 1。 一旦检测到某个位置朝上，我们立即应用逻辑翻转来表示在该索引处执行操作。

 ## 边缘情况

 单个`O`演示有效的移动始终消耗唯一可用的操作并立即终止进程。 该算法处理索引 0，查看有效面朝上，增加答案，并翻转奇偶校验，因此其他位置不再重要。 

像这样的字符串`XXXXXX`表明即使所有卡最初都是面朝下的，但在奇偶校验解释下第一个位置实际上是面朝上的，从而产生了一次操作。 此后，所有后续位置实际上都变为面朝下，并且不可能进一步移动，这与后缀翻转所暗示的模拟行为相匹配。
