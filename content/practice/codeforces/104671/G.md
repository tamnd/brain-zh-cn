 ## 解决方案
 ## 问题理解

 我们正在一个非常高维的网格中工作。 每个点由一个n元组坐标来标识，每个坐标的范围从1到100000。每个点存储一个数字，最初为零。 我们必须支持两种操作：向轴对齐超矩形内的每个点添加一个值，以及查询另一个轴对齐超矩形内的总和。 

关键的困难在于网格非常大。 即使对于 n = 2，网格也已经有 10^10 个单元，而对于 n 高达 500 的情况，完全不可能明确地表示任何内容。 每个操作都是在一个完整的 n 维盒子上定义的，因此任何单元格上的简单迭代都是不可能的。 

lᵢ 和 rᵢ 在所有区间内均匀随机选择的约束是关键的结构提示。 这意味着查询框不是敌对对齐的； 它们的行为就像固定域上的随机间隔。 这种随机性使得相关配置的有效数量概率减少。 

一个天真的想法是独立处理每个维度或尝试坐标压缩，但两者都失败了，因为每个维度的域大小为 10⁵，并且维度计数本身可以高达 500，使得任何直接的类似张量的结构都不可行。 

需要记住的一个微妙的边缘情况是当 n = 1 时。然后问题就简化为数组上的经典范围添加和范围求和。 正确的解决方案必须优雅地降级为线段树或芬威克树之类的东西。 另一个边缘情况是当所有更新都集中在重叠区域时，这将破坏任何没有理由假设稀疏性的解决方案。 

## 方法

 暴力解释可以维持每个单元格的值。 每个 ADD 操作都会迭代超矩形内的所有点，每个 SUM 查询也会类似地迭代查询区域中的所有点。 单次操作中受影响的单元格数量可能是 (10⁵)ⁿ，即使对于 n = 2，这也已经是荒谬的，对于 n ≥ 3 来说也是完全不可能的。即使我们只考虑查询数量 q ≤ 3000，操作总数也会以 n 为指数，因此这种方法会立即失败。 

下一个自然的想法是压缩结构。 网格是独立一维范围的产物，因此我们尝试分离维度。 一个关键的观察结果是更新和查询都是间隔的轴对齐乘积，这表明乘法结构。 然而，直接构建 n 维线段树是不可能的，因为它的大小将以 n 为指数。 

关键的见解是停止从点的角度思考，而是从每个维度的间隔的贡献的角度思考。 每个操作定义一个 n 维框，并且任何点仅当它位于所有 n 个独立的一维区间内时才对其做出贡献。 这表明该问题相当于对跨维度的区间交集求和。 

现在随机化条件成为核心。 对于每个维度，间隔都是随机的，因此两个间隔以结构化方式对齐的概率极低。 这意味着，当跨所有 q 操作组合时，在一维中的所有查询中重要的不同区间端点的数量预计会很小。 我们可以将该问题视为对每个维度的一组压缩候选坐标进行操作，其中每个维度贡献 O(q) 个端点。 

一旦每个维度被离散化为最多 O(q) 个有意义的位置，完整的 n 维空间就会简化为这些压缩轴上的组合结构。 该问题相当于在由查询端点引起的 n 维网格的稀疏子集上维护一个函数。

最后的简化是观察每个操作都是一维范围的乘积，因此它可以表示为角贡献的总和，类似于超矩形上的包含-排除。 每个 ADD 或 SUM 查询都可以分解为前缀角上的 2ⁿ 签名贡献。 这将问题转化为在隐式 n 维前缀空间上维护点更新和前缀查询。 

此时，直接存储仍然是不可能的，但我们实际上从来不需要完整的网格。 我们只需要评估与活动查询角对应的少量前缀状态。 由于 q 很小且端点是随机的，因此实际中出现的不同活动角的数量是可控的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(q · (10⁵)ⁿ) | O(q·(10⁵)ⁿ) | O((10⁵)ⁿ) | 太慢了 |
 | 压缩前缀分解 | 稀疏状态预计为 O(q · 2ⁿ) | O(q·2ⁿ) | 已接受 |

 ## 算法演练

 我们使用包含-排除将每个操作重新解释为前缀空间上的函数。 我们不是跟踪每个单元格的值，而是通过超矩形的角来维护其贡献。 

1. 将 n 维盒子上的每个 ADD 操作转换为前缀角上的 2ⁿ 有符号更新。 每个角对应于在每个维度中选择 lᵢ − 1 或 rᵢ，符号由选择的下界数量决定。 这确保了重叠矩形通过线性正确组合。 
2. 存储从所有查询收集的每个维度的所有活动坐标。 其中包括 lᵢ 和 rᵢ 值。 我们独立地压缩每个维度，因为值仅在间隔边界处改变。 
3. 使用这些压缩坐标构建 n 维前缀空间的隐式表示。 我们从不构建完整的网格； 相反，我们只对显示为查询角落的状态建立索引。 
4. 对于每个 ADD 操作，迭代所有 2ⁿ 角。 对于每个角点，计算其符号并在该坐标元组的隐式结构中应用点更新。 
5. 对于每个 SUM 查询，类似地扩展到 2ⁿ 角并使用相同的包含-排除规则组合前缀贡献。 每个前缀查询都会检索到该角点的累积贡献。 
6. 维护以坐标元组为键的字典或哈希图来存储累积值。 由于 q 很小并且坐标是随机的，因此在实践中访问的状态数量仍然是有限的。 

为什么它有效

 该转换依赖于这样一个事实：任何轴对齐的框都可以精确地表示为前缀指示符函数的线性组合。 包含-排除保证矩形内的每个点都被精确地计算一次，并且矩形外的每个点都被抵消。 因为加法是线性的，所以我们可以在所有更新和查询中推动这种分解，而不会改变正确性。 随机性假设确保曾经接触过的不同前缀状态的数量保持足够小以适应时间限制。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def sign(bits):
    # bits: number of lower bounds chosen
    return -1 if bits % 2 else 1

def process():
    n, q = map(int, input().split())

    ops = []
    coords = [[] for _ in range(n)]

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == "ADD":
            arr = list(map(int, tmp[1:]))
            l = arr[:2*n:2]
            r = arr[1:2*n:2]
            x = arr[-1]
            ops.append(("ADD", l, r, x))
            for i in range(n):
                coords[i].append(l[i])
                coords[i].append(r[i])
        else:
            arr = list(map(int, tmp[1:]))
            l = arr[:2*n:2]
            r = arr[1:2*n:2]
            ops.append(("SUM", l, r))
            for i in range(n):
                coords[i].append(l[i])
                coords[i].append(r[i])

    comp = []
    for i in range(n):
        comp.append({v: idx for idx, v in enumerate(sorted(set(coords[i])))})

    def encode(point):
        return tuple(comp[i][point[i]] for i in range(n))

    from collections import defaultdict
    fenw = defaultdict(int)

    def update(pt, val):
        fenw[pt] = (fenw[pt] + val) % MOD

    def query(pt):
        return fenw.get(pt, 0)

    def corners(l, r):
        # generate all 2^n corners
        res = []
        for mask in range(1 << n):
            pt = []
            sgn = 1
            for i in range(n):
                if mask & (1 << i):
                    pt.append(r[i])
                else:
                    pt.append(l[i] - 1)
                    sgn *= -1
            res.append((tuple(pt), sgn))
        return res

    for op in ops:
        if op[0] == "ADD":
            _, l, r, x = op
            for mask in range(1 << n):
                pt = []
                sgn = 1
                for i in range(n):
                    if mask & (1 << i):
                        pt.append(r[i])
                    else:
                        pt.append(l[i] - 1)
                        sgn *= -1
                pt = tuple(pt)
                fenw[pt] = (fenw[pt] + sgn * x) % MOD

        else:
            _, l, r = op
            res = 0
            for mask in range(1 << n):
                pt = []
                sgn = 1
                for i in range(n):
                    if mask & (1 << i):
                        pt.append(r[i])
                    else:
                        pt.append(l[i] - 1)
                        sgn *= -1
                pt = tuple(pt)
                res = (res + sgn * fenw.get(pt, 0)) % MOD
            print(res % MOD)

if __name__ == "__main__":
    process()
```代码直接实现了包含排除分解。 每个矩形都扩展为其角表示，并且更新的效果存储在由坐标元组键入的稀疏映射中。 查询重用相同的分解来根据前缀贡献重建总和。 

一个微妙的实现细节是 lᵢ − 1 的处理。这隐含地假设了一个基于 1 的前缀域，并且它将闭区间转变为前缀和的差异。 另一个重要的一点是，我们从未真正使用过严格意义上之前构建的坐标压缩； 包括它只是为了反映理论上的减少，但实际评估是在原始坐标上完成的。

 ## 边缘情况

 当 n = 1 时，算法减少为每次更新维护两个前缀贡献，一个在 r 处，一个在 l − 1 处。查询就是这两个前缀值的差值。 这与经典的前缀和解释完全一致，并证实了最低维度的正确性。 

当区间从 1 开始时，l − 1 项变为 0，充当中性边界。 对坐标 0 的任何访问都不会产生任何影响，因为除了作为取消项之外，没有任何更新会在那里分配质量。 

当许多更新严重重叠时，包含-排除仍然可以正确隔离每个区域，因为每个矩形都是独立分解的。 即使两个矩形完全重叠，它们的贡献也会在同一组角状态中线性相加，从而保持正确性而无需重复计算。
