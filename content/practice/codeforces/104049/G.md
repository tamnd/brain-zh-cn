 ## 解决方案
 ## 问题理解

 我们得到一张矩形箔片，表示为尺寸的网格$n \times m$。 有些细胞含有标记为的缺陷`X`，而其他人则干净。 我们想要从这张板材中提取一块符合铸锭资格的矩形金属。 

锭必须满足几何约束：其一侧的长度必须精确$k$。 另一边，我们称之为可变长度，可以自由选择。 然而，有一个质量限制：锭最多可以包含$x$不完美之处。 

任务是确定该可变边长的最大可能值，以便存在至少一个有效的$k \times L$或者$L \times k$包含不超过的子矩形$x$ `X`细胞。 

输入大小约束$n \cdot m \le 10^5$意味着网格足够稀疏$O(nm)$预处理是可以接受的，但是任何尝试独立检查所有子矩形的方法都会太慢。 天真地列举了所有$O(n^2 m^2)$矩形是不可能的，甚至未经预处理的三维滑动窗口也会超出限制。 

一个关键的边缘情况来自于固定尺寸如何与网格边界交互。 如果$k$等于 1，问题就退化为选择一条条带，如果$k$接近于$\max(n,m)$，只有很少的方向是有效的。 另一个微妙的情况是当最佳矩形跨越网格的整个高度或宽度时，因为许多天真的滑动窗口方法意外地假设两个尺寸可以对称变化。 

一个小的说明性案例是一个网格，其中所有缺陷都集中在一列中。 如果$k$是行数，那么每个候选矩形都包含该列，答案完全取决于垂直累积。 在没有前缀结构的情况下重新计算每个矩形的计数的简单方法将错误地或太慢地重复计算相同的列贡献。 

## 方法

 蛮力的想法很简单：修复 a 的每个可能的位置$k$- 高度（或$k$-width) 剥离并计算有多少`X`它包含的单元格，然后在保持在限制范围内的同时尽可能扩展另一个维度$x$。 对于每个起始坐标，我们尝试所有可能的结束坐标并直接从网格中计算缺陷。 

这是正确的，因为它明确地评估每个候选矩形。 然而，每个矩形总和将花费$O(k)$如果天真的计算，并且有$O(nm)$可能的放置位置，给出总体$O(nm \cdot k)$或者更糟糕的复杂性。 在最坏的情况下$k \approx n$，这退化为$O(n^2 m)$，这远远超出了$n \cdot m \le 10^5$允许。 

关键的观察结果是，问题简化为对许多重叠矩形的快速范围求和查询。 一旦我们确定了高度的方向$k$，每个候选矩形对应于一个连续的行窗口，我们只需要知道该窗口内的按列求和。 这建议将每一列压缩为行上前缀和的一维数组，将二维问题转化为这些列聚合上的许多滑动窗口问题。 

我们不是从头开始重新计算总和，而是预先计算每列行上的前缀总和。 那么对于任意固定的行间距高度$k$，我们可以得到每列的缺陷数$O(1)$。 之后，问题就变成了找到总和最多为的最长连续的列段$x$，这是一个标准的两指针滑动窗口问题。 我们对宽度固定为的旋转情况重复相同的推理$k$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O((nm)^2)$最坏的情况|$O(1)$额外 | 太慢了|
 | 前缀+滑动窗口 |$O(nm)$|$O(nm)$| 已接受 |

 ## 算法演练

 我们从两个方向解决问题：固定高度的水平条$k$，并固定宽度的垂直条$k$。 我们对两者都采取最佳答案。 

1. 在网格上构建一个 2D 前缀结构，以便我们可以查询有多少个`X`细胞以恒定的时间存在于柱的任何垂直部分中。 这是通过独立计算每列的行前缀和来完成的。 
2. 对于每个可能的顶行$r$，计算行之间每列的缺陷数$r$和$r + k - 1$。 这会生成一个一维数组，其中每个条目代表将该列包含在$k$- 从行开始的高条$r$。 此步骤必要的原因是，一旦高度固定，列就成为总计数的独立贡献者。 
3. 在此一维数组上，使用带有两个指针的滑动窗口。 在缺陷总数不超过的情况下展开右指针$x$。 每当违反约束时，将左指针向前移动，直到再次满足为止。 在每一步中，记录最大窗口长度。 这是有效的，因为所有值都是非负的，因此扩大窗口只能增加或维持总和。 
4. 转置网格后重复相同的过程，处理固定长度边的情况$k$是水平的而不是垂直的。 这种对称性至关重要，因为该问题允许任一维度精确地$k$。 
5. 返回从两个方向获得的最大长度。 

### 为什么它有效

 一次$k$-条带的高度是固定的，每个可行的锭完全对应于连续的柱段。 任何段的成本都是与列相加的，并且所有贡献都是非负的。 这创建了一个单调的结构：延长一个段永远不会减少缺陷的数量。 因此，滑动窗口保持当前段始终是以右指针结束的最长有效段的不变量，并且当右指针移动时，每个有效段被恰好考虑一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_orientation(grid, n, m, k, x):
    # prefix sums per column
    pref = [[0] * m for _ in range(n + 1)]
    for i in range(n):
        row = grid[i]
        for j in range(m):
            pref[i + 1][j] = pref[i][j] + (1 if row[j] == 'X' else 0)

    best = 0

    for top in range(n - k + 1):
        col_cost = [0] * m
        bottom = top + k
        for j in range(m):
            col_cost[j] = pref[bottom][j] - pref[top][j]

        # sliding window over columns
        l = 0
        s = 0
        for r in range(m):
            s += col_cost[r]
            while s > x:
                s -= col_cost[l]
                l += 1
            best = max(best, r - l + 1)

    return best

def solve():
    n, m, k, x = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    ans1 = solve_orientation(grid, n, m, k, x)

    transposed = [''.join(grid[i][j] for i in range(n)) for j in range(m)]
    ans2 = solve_orientation(transposed, m, n, k, x)

    print(max(ans1, ans2))

if __name__ == "__main__":
    solve()
```该实现首先按列构造前缀和，以便可以在每列的恒定时间内评估任何垂直段。 功能`solve_orientation`然后迭代 a 的所有可能的起始行$k$-height 窗口并将该窗口压缩为一维成本数组。 列上的滑动窗口确保我们始终保持最多一个有效段$x$不完美，贪婪地扩张，只在必要时收缩。 

一个微妙的实现细节是前缀和的索引为`pref[i+1][j] - pref[i][j]`，这可以避免提取高度窗口时出现相差一的错误$k$。 另一个重要的细节是转置：我们没有为水平和垂直情况编写单独的逻辑，而是在旋转网格上重用相同的函数，这可以防止重复的逻辑错误。

 ## 边缘情况

 关键的边缘情况是最佳矩形跨越全部可能的宽度但仅受到少量缺陷的限制。 在这种情况下，滑动窗口在某个点之后永远不会缩小，答案就变成了网格的整个宽度。 该算法自然地处理这个问题，因为右指针继续扩展，而总和保持在$x$，并且没有引入人为停止条件。 

另一种情况是当$k$等于$n$或者$m$。 那么只有一个方向是有效的，并且转置步骤确保我们仍然考虑正确的维度而不重复逻辑。
