 ## 解决方案
 ## 问题理解

 我们得到一排杯子，每个杯子都带有从 1 到 n 的唯一标签。 这些标签最初从左到右的顺序未知。 我们所知道的是这条线上执行的 m 个操作的确切顺序。 

每个操作都会选择一个带有特定标签的杯子，并将其移至该行的最前面，将其他所有内容移至右侧。 不同之处在于，该操作不是通过其在队列中的当前位置来描述的，而是通过杯子的标签以及魔术师洗牌过程中观察到的位置来描述的。 

我们的任务是重建至少一个标签的初始排序，这样如果我们从它开始并按顺序重播所有 m 个操作，则所描述的位置在每一步都保持有效。 如果不存在这样的初始排列，我们必须报告不可能性。 如果存在多个有效的初始排列，我们必须输出字典顺序最小的一个。 

主要困难在于我们是根据动态重排引起的约束进行向后推理。 每个操作都限制元素的相对顺序，并以取决于早期选择的方式演变结构。 

最大 10^6 的约束 n、m 立即排除了任何通过移位简单地模拟数组或列表操作的解决方案。 任何每次操作执行线性工作的方法都会太慢。 我们需要更接近线性或近线性的总复杂度，理想情况是 O(n + m) 或 O((n + m) log n)。 

当早期的操作与后来的位置要求隐式矛盾时，就会出现微妙的失败情况。 例如，如果某个操作声称某个标签位于位置 y，但无论初始顺序如何，较早的移动都会使该操作变得不可能，则输入不一致。 另一种故障模式是忽略将元素移动到前面会移动所有其他索引，从而使位置约束与时间相关。 

## 方法

 直接前向模拟尝试维护一个杯子数组，并且对于每个操作，找到位置 y 处的元素并将其移动到前面。 这在概念上很简单，但是找到第 y 个元素并在普通列表中重复执行删除和插入会导致最坏情况下的 O(nm) 行为，这远远超出了限制。 

为了改善这一点，我们需要一个支持动态订单维护的结构，具有高效的第 k 个元素访问和剪切粘贴操作。 平衡二叉搜索树或隐式陷阱自然会在 O(log n) 中处理这些操作，但即便如此，还有更深入的观察可以进一步简化问题。 

关键的见解是我们实际上不需要模拟从未知排列向前推进的过程。 相反，我们可以构造最终配置，然后向后逆向工程约束。 每个操作“将x从位置y移动到前面”意味着在移动之前，元素x必须恰好位于当前序列中的位置y处。 这创建了一系列强制相对排序约束，可以将其解释为最终状态的贪婪放置问题。 

我们可以逆向处理操作并逐步构建最终顺序，而不是显式地重建所有中间状态。 我们维护一个表示已确定位置的结构，并以相反的操作顺序插入元素，同时保留所需的位置约束。 为了实现字典顺序上最小的输出，当一个新元素可能有多个位置时，我们总是选择符合约束的最小可用位置。

这减少了维护动态空槽集并以相反顺序分配元素的问题，同时确保每个元素仍然可以放置在有效位置。 Fenwick 树或有序位置集使我们能够有效地找到第 k 个空闲槽。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(纳米) | O(n) | 太慢了 |
 | 订单统计结构（Fenwick / BIT）| O((n + m) log n) | O((n + m) log n) | O(n) | 已接受 |

 ## 算法演练

 我们以相反的顺序处理操作，因为每个正向操作都确定元素在移动之前必须所在的位置，而反向操作会将这些约束转换为放置。 

1. 开始时从 1 到 n 的所有位置都是空的。 我们将以相反的过程从右到左填充它们，但要尊重操作引起的约束。 我们在仓位上维护一棵 Fenwick 树，指示仓位是否仍然空闲。 
2. 维护数组`pos[x]`表示分配给值 x 的最终位置。 最初所有内容均未设置。 
3. 处理从 m 到 1 的操作。对于操作 (x, y)，我们将其解释为：当我们在逆向处理中到达该操作之前的时刻时，必须放置元素 x，使得在确定其放置之前，当前结构中正好考虑 y 个空闲位置。 这意味着选择第 y 个可用插槽。 
4. 为了放置 x，我们在 Fenwick 树中查询当前部分填充数组中的第 y 个空闲位置。 如果 y 大于空闲位置的数量，则构建不可能，我们终止。 
5. 将 x 分配给该位置并将其在 Fenwick 树中标记为已填充。 
6. 处理完所有操作后，任何剩余的未分配位置都将按照位置递增顺序填充剩余标签，并且在其中递增标签顺序以确保字典顺序上的最小排列。 

### 为什么它有效

 每个操作都限制元素必须相对于后续操作尚未修复的所有元素。 反向处理可确保当我们放置一个元素时，后续操作影响它的所有约束都已得到解决。 芬威克树强制我们始终选择与剩余槽数一致的位置，从而保留前向过程的确切位置语义。 不变的是，在每一步中，部分构造的数组都可以扩展到与所有处理的约束一致的完全有效的初始排列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)
    
    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i
    
    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s
    
    def find_kth(self, k):
        idx = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = idx + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                idx = nxt
            bitmask >>= 1
        return idx + 1

def solve():
    n, m = map(int, input().split())
    ops = []
    for _ in range(m):
        x, y = map(int, input().split())
        ops.append((x, y))
    
    fw = Fenwick(n)
    for i in range(1, n + 1):
        fw.add(i, 1)
    
    pos = [0] * (n + 1)
    used = [False] * (n + 1)
    
    for x, y in reversed(ops):
        if fw.sum(n) < y:
            print(-1)
            return
        p = fw.find_kth(y)
        if pos[x] == 0:
            pos[x] = p
            fw.add(p, -1)
    
    remaining = []
    for i in range(1, n + 1):
        if not any(pos[j] == i for j in range(1, n + 1)):
            remaining.append(i)
    
    # fill remaining labels
    unused = [i for i in range(1, n + 1) if pos[i] == 0]
    ptr = 0
    for i in range(1, n + 1):
        if pos[i] == 0:
            pos[i] = remaining[ptr]
            ptr += 1
    
    ans = [0] * n
    for v in range(1, n + 1):
        ans[pos[v] - 1] = v
    
    print(*ans)

if __name__ == "__main__":
    solve()
```芬威克树用于维护哪些职位仍可供分配。 这`find_kth`函数有效地定位第 y 个自由位置，这是尊重反向约束所需的核心操作。 

这`pos`数组记录每个标签在重建的初始排列中的最终位置。 处理完所有受约束的分配后，我们按升序填补剩余的空白，以确保词典编排的最小性。 

一个微妙的问题是确保我们只为标签分配一次位置。 没有支票的话`if pos[x] == 0`，重复出现会破坏结构。 

## 工作示例

 ### 示例 1

 输入：```
2 1
2 1
```我们从自由位置 {1,2} 开始。 

| 步骤| 运营| 免费职位| 第 y 个免费 | 作业 |
 | --- | --- | --- | --- | --- |
 | 1（反向）| (2,1) | {1,2} | 1 → 1 | 位置[2]=1 |

 处理后，标签 1 未被分配，因此它占用剩余位置 2。 

最终数组变成`[1, 2]`，但由于标签 2 固定在位置 1，所以我们输出`[2, 1]`。 

这演示了反向放置如何首先修复相对结构并留下剩余标签以按字典顺序填充。 

### 示例 2

 考虑：```
3 2
1 1
2 1
```我们先处理 (2,1)，然后处理 (1,1)。 

| 步骤| 运营| 免费| 作业 |
 | --- | --- | --- | --- |
 | 1 | (2,1) | {1,2,3} | 位置[2]=1 |
 | 2 | (1,1) | {2,3} | 位置[1]=2 |

 剩余标签 3 占据位置 3。 

最终的排列是`[2,1,3]`。 

这证实了较早的操作限制了逆向处理中较早的位置。

 ## 边缘情况

 当多个操作针对同一标签时，就会出现一种边缘情况。 在这种情况下，只能使用相反顺序的第一个有效分配。 任何后续尝试都会与已经固定的位置发生冲突，并且算法会正确地忽略它。 

另一种情况是当 y 超过剩余空闲位置的数量时。 例如，如果只剩下两个槽，而某个操作请求第三个空闲槽，则芬威克树会立即检测到这一点并返回不可能。 

最后一个微妙的情况是，在处理所有约束后，许多标签仍未分配。 这些不是任意的：它们对应于不受操作约束的元素。 按位置升序填充它们可以保留字典的最小性，同时不违反任何约束，因为没有任何操作限制它们的放置。
