 ## 解决方案
 ## 问题理解

 该问题模拟了两个用电量为正整数的家庭。 电力公司采用累进电价：前 100 CWh 每台花费 2 Americus，接下来的 9,900 CWh 每台花费 3 Americus，接下来的 990,000 CWh 每台花费 5 Americus，超过 1,000,000 每单位花费 7 Americus。原来的问题给了我们两个数字，`A`和`B`。`A`是如果在征收关税之前将两个家庭的消费合并起来所产生的账单。`B`是他们各自账单之间的绝对差异。 我们保证恰好一对消费产生这两个值，并且我们必须输出较小家庭的个人账单。 输入包含多个测试用例并以`0 0`。 

第一个任务是恢复总消耗`A`。 这是可能的，因为关税函数是严格递增的。 一旦知道总消耗量，就可以调用它`C`，两个单独的消费必须是`x`和`C - x`。 由于我们承诺我们的消耗不大于邻居的消耗，所以我们只需要考虑`1 <= x <= C / 2`。 

数字界限是`A <= 10^9`。 这意味着总消耗量约为 10^8，因为最高关税为每单位 7 美元。 对所有可能的情况进行线性扫描`x`因此，一个测试用例需要数千万次迭代。 由于 1 秒的限制，工作量太大了，尤其是在 Python 中。 相反，关税的结构为我们提供了一个单调函数，它允许我们使用二分搜索并将搜索次数减少到大约 30 次迭代。 

在几种边界情况下，直接实施可能会失败。 第一个是最小的有效非终止情况。 为了```
6 2
```总消耗量为 3，因为`bill(3) = 6`。 唯一可能的分割是 1 和 2，其账单是 2 和 4，所以答案是```
2
```假设每个测试用例都有足够大的消耗来进入第二关税范围的粗心实现可能会错误地计算。 

正好 100 单位的关税边界是差一误差的另一个常见来源。 考虑```
200 4
```总消费是 100。唯一的分割是 49 和 51。他们的账单是 98 和 102，相差 4，所以答案是```
98
```使用`100`因为这里需要的是第一个范围的大小，而不是按照速率 2 精确充电前 100 个单位。 

第一个关税范围之后的边界同样重要。 201台综合消费已账单`503`，因为前 100 个单位的成本为 200，接下来的 101 个单位的成本为 303。如果解决方案意外地对第 100 个单位使用了第二个费率，则以后的每个计算都会发生变化。 

最高关税范围也很重要。 例如，```
4979977 4979968
```对应于 1,000,010 和 1 的消费，因此较小的家庭支付 2。合并消费跨越 1,000,000 单位边界，因此必须正确实施最终关税分支。 这种边界情况非常有用，因为实现在普通值上可能看起来正确，但一旦消耗超过 1,000,000，就会失败。 

最后，`0 0`这不是一个普通的案例。 它是输入终止符。 特别是，尽管平等法案会产生`B = 0`，常规测试用例有阳性`B`，因此我们应该期望的唯一零差异输入是终止对。 

## 方法

 一个简单的解决方案首先将`A`计入总消费`C`，然后尝试一切可能的较小消耗`x`从 1 到`C / 2`。 对于每个候选人，它将计算`bill(x)`和`bill(C - x)`，比较它们的差异`B`，并在找到所需差异时停止。 这是可行的，因为每个可能的分割都会被显式检查，并且该语句保证只有一个分割是有效的。 

问题在于搜索空间的大小。 什么时候`A`接近于`10^9`，对应的总消费量约为1.43亿台。 其中一半是大约 7100 万个候选分裂。 每个候选者至少需要几次算术运算和费率评估，因此最坏的情况是每个测试用例大约 7100 万次迭代。 这与 1 秒限制不兼容。 

关键的观察结果是，当我们移动分割时，两张钞票之间的差异单调变化。 让`D(x) = bill(C - x) - bill(x)`为了`x <= C / 2`。 作为`x`增加，小家庭消费更多，大家庭消费减少。 因为`bill`是严格递增的，`bill(x)`增加同时`bill(C - x)`减少。 最后，`D(x)`严格减少。 

这将暴力搜索变成了二分搜索。 如果`D(x)`大于`B`，我们选择的家庭还是太小，所以我们增加`x`。 如果`D(x)`小于`B`，我们把较小的家庭弄得太大了，所以我们减少了`x`。 唯一解决方案保证意味着最终找到准确的目标。 

还有一种更有用的简化。 我们不需要搜索可能的总消耗来恢复`C`。 关税函数可以直接反转，因为每个范围都有固定的价格。 例如，高于 29,900 但最多 4,979,900 的账单对应于`10,000 + (A - 29,900) / 5`单位。 自从`A`保证来自真实的综合消费，划分是准确的。

 | ---| ---| ---| ---|
 | 蛮力 | O(C)| O(1) | O(1) | 太慢了|
 | 最佳| O(log C) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`A`和`B`。 如果两者都为零，则停止，因为这是标记输入结束的标记。 
2. 转换合并账单`A`计入综合消费`C`。 反向关税是分段的，使用三个关税边界处的累积成本 200、29,900 和 4,979,900。 
3. 将二分查找范围设置为`lo = 1`和`hi = C // 2`。 我们只搜索总消费的一半，因为该问题确定我们的家庭的消费不超过其邻居。 
4. 选择`mid = (lo + hi) // 2`并让两个消费为`mid`和`C - mid`。 
5. 计算两个单独的账单及其差额，`diff = bill(C - mid) - bill(mid)`。 第二个法案至少是第一个，因为`mid <= C - mid`，因此在搜索中不需要绝对值。 
6. 如果`diff == B`，我们找到了唯一的分割，并且`bill(mid)`是必需的答案。 
7. 如果`diff > B`， 增加`mid`通过移动`lo`到`mid + 1`。 增加小家庭的消费使两个账单更接近，从而减少`diff`。 
8.如果`diff < B`， 减少`mid`通过移动`hi`到`mid - 1`。 我们在平等消费方面已经走得太远，因此帐单差异已变得小于要求。 

不变的是正确的较小消耗仍然保留在内部`[lo, hi]`。 功能`D(x)`是严格递减的，所以每次比较都会告诉我们哪一半不能包含答案。 什么时候`D(mid) > B`，每个等于或低于的值`mid`产生的差异至少同样大，所以答案一定是在右边。 什么时候`D(mid) < B`，每个值等于或高于`mid`产生的差异不会更大，所以答案一定在左边。 由于保证有效的分割是唯一的，二分查找不能丢弃它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def bill(energy):
    if energy <= 100:
        return energy * 2

    result = 200
    energy -= 100

    if energy <= 9900:
        return result + energy * 3

    result += 9900 * 3
    energy -= 9900

    if energy <= 990000:
        return result + energy * 5

    result += 990000 * 5
    energy -= 990000

    return result + energy * 7

def consumption_from_bill(amount):
    if amount <= 200:
        return amount // 2

    if amount <= 29900:
        return 100 + (amount - 200) // 3

    if amount <= 4979900:
        return 10000 + (amount - 29900) // 5

    return 1000000 + (amount - 4979900) // 7

def solve():
    while True:
        A, B = map(int, input().split())

        if A == 0 and B == 0:
            break

        total = consumption_from_bill(A)

        lo = 1
        hi = total // 2

        while lo <= hi:
            mid = (lo + hi) // 2

            smaller_bill = bill(mid)
            larger_bill = bill(total - mid)
            diff = larger_bill - smaller_bill

            if diff == B:
                print(smaller_bill)
                break

            if diff > B:
                lo = mid + 1
            else:
                hi = mid - 1

if __name__ == "__main__":
    solve()
```这`bill`函数使用累积成本实现累进费率。 前 100 台之后，前 200 台 Americus 已收费。 接下来的 9,900 个单位之后，累计成本为`200 + 9900 * 3 = 29,900`。 再经过 990,000 个单位后，就变成了`29,900 + 990000 * 5 = 4,979,900`。 这些常数让每个帐单计算在常数时间内运行。 

这`consumption_from_bill`函数反转了这些相同的边界。 例如，如果`amount`是在 29,901 到 4,979,900 之间，前 10,000 单位已经占了 29,900 Americus，所以剩余的数量除以 5 并加到 10,000。 

二分查找故意使用消费而不是金钱。 关税是非线性的，因此尝试直接对账单差异进行二分搜索而不首先恢复总消费会使这种关系更难以表达。 一次`total`众所周知，这两种消耗总是会加到该固定值上。 

搜索使用`bill(total - mid) - bill(mid)`而不是`abs(...)`。 因为`mid <= total // 2`，第二个家庭的消费至少与第一个家庭一样多，账单功能不断增强。 因此，较大的账单是预先知道的。 

Python 整数具有任意精度，因此不存在溢出问题。 无论如何，最大的中间值完全在 Python 的整数表示范围内。 使用`sys.stdin.readline`还可以避免测试用例较多时不必要的输入开销。

import io

def bill(energy):
    if energy <= 100:
        return energy * 2
    if energy <= 10000:
        return 200 + (energy - 100) * 3
    if energy <= 1000000:
        return 29900 + (energy - 10000) * 5
    return 4979900 + (energy - 1000000) * 7

def consumption_from_bill(amount):
    if amount <= 200:
        return amount // 2
    if amount <= 29900:
        return 100 + (amount - 200) // 3
    if amount <= 4979900:
        return 10000 + (amount - 29900) // 5
    return 1000000 + (amount - 4979900) // 7

def solve_data(data: str) -> str:
    inp = io.StringIO(data)
    out = []

    while True:
        line = inp.readline()
        if not line:
            break

        A, B = map(int, line.split())

        if A == 0 and B == 0:
            break

        total = consumption_from_bill(A)

        lo = 1
        hi = total // 2

            mid = (lo + hi) // 2

            large = bill(total - mid)
            diff = large - small

            if diff == B:
                out.append(str(small))
                break

            if diff > B:
                lo = mid + 1
            else:
                hi = mid - 1

    return "\n".join(out)

 ## 边缘情况

 对于最小有效输入`6 2`，反向关税将 6 Americus 转换为 3 个总单位。 二分查找开始于`lo = 1`和`hi = 1`， 所以`mid = 1`。 两个消耗量是 1 和 2，他们的账单是 2 和 4，差值正好是 2。算法立即打印 2。没有假设任何一个家庭消耗的电力足以达到第二个电价范围。 

对于第一个关税边界，考虑`200 4`。 反函数返回 100 个单位，因为前 100 个单位的成本恰好为 200。如果间隔表示为，则二分搜索测试唯一可能的较小消耗 50`1..50`，最终找到唯一的分割 49 和 51。他们的账单是 98 和 102，给出所需的差值 4。计算将单元 100 视为第一个范围的一部分，将单元 101 视为按费率 3 收费的第一个单元。 

对于跨越最高边界的情况，请考虑`4979977 4979968`。 合并后的账单将转换为 1,000,011 单位。 有效的分割是 1 和 1,000,010。 第一个家庭支付 2。第二个家庭支付`4,979,900 + 10 * 7 = 4,979,970`，因此差异为 4,979,968。 因此，搜索发现较小的消耗为 1 并输出 2。这既执行了反向关税的最终分支，也执行了正向关税的最终分支。 

对于大范围的情况`999999996 999999987`，合计消耗为143,145,728。 有效的分割是 1 和 143,145,727。 较小的钞票是 2，而较大的钞票是 999,999,989，相差 999,999,987。 尽管总消耗量超过 1.43 亿个单位，但二分搜索只需要对数次迭代，而不是一一扫描那些可能的分割。 

这`0 0`输入是在任何费率转换或二分搜索之前处理的。 它立即终止循环，因此不会意外地被解释为一对零消费家庭。 这种区别很重要，因为常规测试用例具有积极的意义`A`和`B`， 尽管`0 0`仅保留作为结束标记。
