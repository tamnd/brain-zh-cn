 ## 解决方案
 ## 问题理解

 我们有一叠卡片，其中包含标记为`1`通过`n`，以某种排列出现。 魔术师必须按照递增的标签顺序丢弃纸牌，因此纸牌`1`必须先弃牌，然后再出牌`2`， 等等。 

只有最上面的牌可以被丢弃。 要改变哪张牌位于顶部，魔术师可以将当前顶部的牌移动到底部，或者将当前底部的牌移动到顶部。 移动一张卡片的成本恰好是它的标签。 丢弃卡不需要任何费用。 

任务是找到移除整个堆栈的最小总旋转成本。 官方输入包含几个测试用例，其中`n`最多`10^5`对于每个案例和每个标签`1`通过`n`只出现一次。 原始竞赛声明和官方问题审查确认了排列结构、示例案例和预期的芬威克树方法。 

这`10^5`界限排除了显式模拟每次旋转的情况。 如果我们花`O(n)`计算一张卡的成本并对所有卡重复计算的时间`n`卡，最坏的情况是`10^10`基本操作。 官方的评测也给出了同样的评价`O(n^2)`估计并确定这太慢了。 我们需要将每张卡的成本计算减少到对数时间。 

有几种边界情况很容易处理不当。 如果所需的卡已经在顶部，则成本为零。 例如，```
2
1 1
2 1 2
```有输出```
0
0
```对于这两种情况。 粗心的实施可能会对所需的卡本身收费，但丢弃最上面的卡不会产生任何费用。 

卡片也可以位于底部。 例如，```
1
3 3 2 1
```有输出```
3
```卡片`1`位于底部，因此它本身必须从下到上移动，成本较高`1`。 丢弃后，卡`2`处于底部且成本`2`移动到顶部。 卡片`3`已经在顶部，总共给出了`3`。 忘记从底部拿出的牌也必须移动是一个常见的错误。 

第一个和最后一个位置也形成一个圆形边界。 例如，```
1
4 2 3 4 1
```有输出```
5
```卡片`1`位于底部，因此将其直接移至顶部成本`1`。 之后，打卡`2`位于顶部，其次是`3`和`4`，所以剩余的搬迁成本`0`。 实际上，这给出了总计`1`， 不是`5`，说明为什么必须从当前顶部而不是从原始的第一个位置来推理圆形结构。 正确的实现必须在每次删除后更新顶部位置。 

为了`n = 1`，唯一的一张牌已经在最上面，答案是零。 这也是唯一一个在空洞意义上“完全平等”的法律实例，因为该问题要求每个标签都是唯一的。 输入如`3 2 2 2`不是此问题的有效测试用例。 

## 方法

 直接解决方案保持每个标签的原始位置。 要移除下一张所需的卡片，我们可以沿任一方向扫描当前堆栈，添加所有必须移动的卡片的标签。 由于有多达`n`卡，一次移除即可取`O(n)`时间。 对所有人重复此操作`n`清除量给出`O(n^2)`时间，可以接近`10^10`操作时`n = 10^5`。 这远远超出了三秒竞赛解决方案所能承受的范围。 官方竞赛评论准确地描述了这种强力策略及其二次运行时间。 

蛮力之所以有用，是因为它暴露了贪婪的结构。 一旦我们决定接下来必须移除哪张牌，就只有两种可能的方式来暴露它：重复地从上到下移动牌，或者重复地从下到上移动牌。 应该选择成本较低的方向。 当所需的牌被丢弃后，剩余的牌无论使用哪个方向都具有相同的循环顺序。 走更长的路并不能创造更好的未来安排，因为这两种选择都会留下完全相同的剩余卡牌顺序进行轮换。 官方评论对贪婪选择也做出了同样的观察。 

昂贵的部分并不是贪婪的决定本身。 昂贵的部分是计算移动标签的总和。 每个可能的轮换成本都是原始位置的连续部分的总和，删除的牌的贡献为零。 这正是 Fenwick 树支持的操作：删除卡片时点更新，以及前缀或范围总和`O(log n)`。 

我们还储存`pos[x]`, 卡的原始位置`x`。 堆叠仅通过旋转和删除来改变，因此卡片永远不会改变其在剩余卡片中的相对位置。 因此，它的原始索引足以确定哪些幸存的卡片位于它和之前删除的卡片之间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.将每张卡的原始位置存储在`pos`。 还构建一个 Fenwick 树，其中包含当前每张活动卡在其原始位置的值。 该树用零表示已删除的卡，因此范围总和会自动忽略已删除的所有内容。 
2. 按顺序处理所需的卡片`1, 2, ..., n`。 保持`prev`，先前丢弃的牌的原始位置。 在任何牌被丢弃之前，使用`prev = 0`。 这表示紧邻第一张卡之前的位置，因此输入中的第一张卡是当前的顶部。 
3.让`q = pos[x]`为当前需要的卡的原始位置。 考虑首先从上到下移动卡片。 如果`q > prev`，移动的牌正是从`prev + 1`通过`q - 1`。 如果`q < prev`，路径环绕末端，因此移动的卡片是位置`prev + 1`通过`n`，随后是位置`1`通过`q - 1`。 
4. 查询 Fenwick 树以获取这些卡片的总和。 打电话给这个`forward`。 这些正是在打牌之前必须从上到下移动的牌`x`到达顶部。 
5.另一个方向就更容易了。 每张当前活动的卡要么属于正向路径，要么属于相反路径，并且这两条路径将参与到达的卡分开`x`。 因此，朝相反方向前进的成本为`total - forward`， 在哪里`total`是当前所有活动卡牌的总和。 这包括`x`本身当`x`必须从下到上移动，这正是规则所要求的。 
6. 添加`min(forward, total - forward)`到答案。 更便宜的方向对于这种移除来说是最佳的，因为两个方向在之后留下的剩余卡片的循环顺序相同。`x`被丢弃。 
7. 删除`x`从芬威克树中添加`-x`在位置`q`, 减去`x`从`total`，并设置`prev = q`。 现在将相对于这个新起点评估下一张所需的卡片。 

### 为什么它有效

 不变的是，每次删除后，芬威克树都包含在其原始位置的幸存卡片，而`prev`标识循环顺序中紧邻当前顶部之前的原始位置。 为了下一个目标`x`, 之间的卡片`prev`和`pos[x]`沿一个圆形方向恰好是必须移动才能暴露的卡片`x`从那个方向。 相反的方向包含第一条路径中未计入的所有剩余牌，包括`x`当它必须从下到上移动时，它本身。 因此，计算出的两个成本正是公开的两种合法方式`x`，并且取最小值是最佳的。 删除后`x`，所有其他卡的相对循环顺序不变，因此对于下一个目标，不变量仍然成立。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(a):
    n = len(a)

    # pos[x] = original position of card x, using 1-based positions.
    pos = [0] * (n + 1)

    # Fenwick tree.
    bit = [0] * (n + 1)

    for i, x in enumerate(a, 1):
        pos[x] = i
        bit[i] = x

    # O(n) Fenwick construction.
    for i in range(1, n + 1):
        j = i + (i & -i)
        if j <= n:
            bit[j] += bit[i]

    def prefix_sum(i):
        result = 0
        while i > 0:
            result += bit[i]
            i -= i & -i
        return result

    total = n * (n + 1) // 2
    answer = 0
    prev = 0

    for x in range(1, n + 1):
        q = pos[x]

        # Cost when rotating top -> bottom.
        if q > prev:
            forward = prefix_sum(q - 1) - prefix_sum(prev)
        else:
            forward = (
                total
                - prefix_sum(prev)
                + prefix_sum(q - 1)
            )

        backward = total - forward
        answer += min(forward, backward)

        # Discard x.
        i = q
        while i <= n:
            bit[i] -= x
            i += i & -i

        total -= x
        prev = q

    return answer

def main():
    t = int(input())
    out = []

    for _ in range(t):
        data = list(map(int, input().split()))
        n = data[0]
        a = data[1:1 + n]
        out.append(str(solve_case(a)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```这`pos`array 实现了从卡片标签到其原始位置的反向查找，对应于算法所需的位置跟踪。 由于旋转不会改变幸存卡牌的相对顺序，因此无需物理旋转 Python 列表。 

当该卡仍然存在时，芬威克树包含其原始位置的卡值。 当一张牌被丢弃时，它的价值会在一个索引处被减去。 然后前缀总和给出了幸存卡牌的任何连续部分的成本`O(log n)`时间。 

最初的芬威克树是在`O(n)`而不是表演`n`分离`O(log n)`更新。 这对于渐近解不是必需的，但它减少了 Python 中的初始化开销。 

表达式为`forward`故意使用独占端点。 如果`q > prev`,`prefix_sum(q - 1) - prefix_sum(prev)`包含职位`prev + 1`通过`q - 1`，不包括之前删除的卡牌和目标卡牌。 如果`q < prev`，路径环绕，因此代码在后面添加后缀`prev`到前面的前缀`q`。`total`是仍在牌堆中的所有牌的总和。 由于两个可能的旋转方向划分了活动卡，因此反向成本很简单`total - forward`。 这也是为什么目标卡牌从底部到达时会包含在反向成本中的原因。 

所有成本都可能比 32 位整数大得多。 为了`n = 10^5`，总成本可以是`n^3`，因此 Python 的任意精度整数可以方便地处理所需的范围。

## 边缘情况

 对于单张卡来说，```
1
1 1
```目标卡已经在顶部。 前向间隔为空，因此其成本为`0`。 然后卡被移除并且算法终止。 答案是`0`。 

对于底部的卡片，```
1
3 3 2 1
```第一个目标是`1`，在位置`3`。 前进的方向需要移动`3`和`2`，而相反方向移动底牌`1`直接到顶部。 后者的成本`1`，所以卡`1`因成本原因被移除`1`。 剩余的堆栈有`3, 2`、和卡`2`可以从底部移动到顶部以节省成本`2`。 卡片`3`那么已经在上面了。 总计为`3`。 

当目标位于原始数组中先前删除的位置之前时，路径将环绕末尾。 假设之前删除的卡片位于位置`5`下一个目标位于位置`2`。 前进路径由位置后幸存的牌组成`5`，后面是该位置之前的剩余牌`2`。 Fenwick 查询将其处理为两个范围，而相反的方向是通过从活动总计中减去该成本来获得的。 

当目标紧接在前一个删除位置之后时，向前间隔为空。 例如，在已经排序的堆栈中，删除卡片后`2`， 卡片`3`立即位于顶部。 芬威克表达式`prefix(q - 1) - prefix(prev)`变为零，因为两个端点描述相同的边界。 这避免了相邻卡的特殊情况。 

即使卡片消失，删除的位置也必须保留在坐标系中。 芬威克树自然地通过在删除的位置存储零来处理这个问题。 每次删除后物理移动阵列都会破坏原始位置信息并使解决方案返回二次行为。 

最后，重复标签并不是有效问题的边缘情况。 输入如```
