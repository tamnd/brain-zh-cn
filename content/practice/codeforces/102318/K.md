 ## 解决方案
 ## 问题理解

 我们收集了`n`项目类型。 物品`i`价格精确到小数点后两位，并且在构建疯狂购物时我们准确选择`k`按顺序排列的项目。 每个项目类型都可以重复选择，只要项目索引序列不同，两个大礼包就不同。 选择的顺序很重要。 

对于每个目标价格`X`，我们需要长度的数量-`k`其商品价格加起来正好等于的序列`X`。 答案需要模数`997`。 

查看数字界限的有用方法是停止考虑美元并完全以美分为单位。 商品价格均为小整数，每次查询最多`$500.00`，因此每个查询对应于一个介于`1`和`50000`。 尽管狂欢的总价可能要高得多，但系数高于度数`50000`永远不能对答案做出贡献，并且可以在每次多项式乘法之后被丢弃。 

可以有多达`10000`项目类型和`10000`选定的职位。 直接枚举有`n^k`可能的序列。 在最大值时，这是`10000^10000 = 10^40000`，所以即使描述所有可能性也是不可行的。 即使是针对所选项目的数量和总价值的动态规划也将需要大约`k * 50000`，已经存在了`5 * 10^8`在考虑商品价格的转变之前先说明情况。 

隐藏的结构是有界的价格范围。 我们可以存储每个价格有多少个项目索引，而不是单独存储每个项目。 该频率数组自然是多项式的系数数组。 将该多项式提升为`k`然后精确计算我们需要的序列。 

一些边缘情况可能会悄无声息地破坏实现。 

考虑一件物品的价值`⟦PROTECT_11⟧3.00`。```
1
1
1.00
3 1
3.00
```答案是`1`，因为唯一可能的序列是`(1, 1, 1)`。 将项目类型视为不同值并意外禁止重复选择的实现将错误地返回零。 

现在考虑具有相同价格的两种不同商品。```
1
2
1.00
1.00
2 1
2.00
```答案是`4`。 这四个序列是`(1,1)`,`(1,2)`,`(2,1)`， 和`(2,2)`。 基于频率的多项式可以正确处理这个问题，因为`x^100`是`2`，平方得到系数`4`在`x^200`。 仅存储不同价格并失去多样性的实现将错误地返回`1`。 

查询也可以小于最小可能总和。```
1
2
2.00
3.00
2 1
1.00
```答案是`0`，因为每次两件物品的狂欢至少花费`$4.00`。 如果粗心的实现只计算最大商品价格的多项式，而不是最大请求的总价，那么当其索引假设错误时，也可能会错误地处理这种情况。 

最后，值是十进制字符串，因此直接使用二进制浮点数作为多项式索引是不安全的。 价格如`1.10`必须准确地变成`110`美分。 解析与`float`然后乘以`100`可能会引入表示错误。 正确的转换是将字符串解析为十进制文本并构造整数分。 

最初的竞赛声明给出了`n <= 10000`,`k <= 10000`,`q <= 10000`，并且查询值高达`$500.00`。 竞赛的官方问题审查明确指出，这些异常小的货币和模数界限是导致多项式表示和基于 FFT 的乘法的线索。 

## 方法

 蛮力方法直接遵循定义。 对于每一个`k`职位，选择其中一项`n`项目索引，计算结果总数，并增加该总数的答案。 这是正确的，因为每一种可能的疯狂购物都恰好对应于递归生成的一个序​​列，包括重复的项目索引和不同的订单。 

问题在于序列的数量。 有`n^k`其中。 和`n = k = 10000`，这变成了`10000^10000 = 10^40000`序列，远远超出任何实际计算。 官方审查使用这一精确观察来排除枚举。 

一个自然的改进是动态规划。 让`dp[j][s]`计算长度-`j`具有总价值的序列`s`。 计算`dp[j][s]`，我们会考虑每件商品的价格`v`并添加`dp[j-1][s-v]`。 这减少了对的指数依赖性`k`，但仍然为不同价格的数量留下了一个因素。 和`k`相关总和范围均在`50000`，这个方法太大了。 

关键的观察是，选择一个项目会在每个位置独立地贡献其价格。 让`P(x) = c_1 x^1 + c_2 x^2 + ...`在哪里`c_v`是价格为的项目指数的数量`v`美分。 将两个副本相乘`P`为第一个位置选择一个项目，为第二个位置选择一个项目。 系数为`x^s`因此计算所有两项序列的总数`s`美分。 

同样的论点反复适用。 系数为`x^s`在`P(x)^k`正是长度的数字-`k`疯狂购物，其总价值为`s`美分。 这正是每次查询所需的数量。 

剩下的困难是多项式乘法。 两个长度约为的数组的标准卷积`50000`大约需要二次时间`50000^2 = 2.5 * 10^9`一次乘法的系数运算。 这已经太慢了，而且求幂需要多次乘法。 

FFT 将一项多项式乘法减少为`O(N log N)`。 自从`k`可以达到`10000`，我们还使用二进制求幂，将多项式乘法的次数减少到`10000`只到`O(log k)`, 最多大约`28`乘法。 官方评论准确地描述了频率多项式、FFT 卷积和快速求幂的这种组合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(n^k)`|`O(k)`| 太慢了|
 | DP 头寸和金额 |`O(k * S * n)`|`O(S)`| 太慢了|
 | 使用 FFT 进行多项式求幂 |`O(S log S log k)`|`O(S)`| 已接受 |

 这里`S = 50000`，以美分表示的最大查询。 FFT 实现实际上使用足够大的二次幂变换大小来进行卷积，最多可达`131072`对于这个问题。 官方评论给出了相同的变换大小界限。 

## 算法演练

 1. 将每个商品的价格从美元转换为美分，并构建频率数组`P`， 在哪里`P[v]`是精确成本的项目索引的数量`v`美分。 

该系数是一个频率而不仅仅是一个布尔指标，因为具有相同价格的两个不同的项目指数代表两种不同的选择。 
2. 读取所有查询，将其目标值转换为分，然后令`S`是最大的请求目标。 

我们只需要通过度的系数`S`。 任何次数大于的项`S`永远不会影响查询，并且所有价格都是正数，因此丢弃这些术语是安全的。 
3. 减少各系数`P`模数`997`。 

稍后将使用浮点 FFT 算法执行多项式乘法，但仅需要模数数学系数`997`。 
4. 计算`P(x)^k`使用二进制求幂。 

从结果多项式开始`R(x) = 1`。 尽管`k`非零，如果设置了其最低位，则相乘`R`通过当前的功率`P`。 然后对当前功率进行平方并移动`k`就一点点。 

这取代了`k`多项式乘法最多乘以位数的两倍`k`。 
5. 通过 FFT 将多项式乘法实现为卷积。 

如果`A`和`B`有学位`a`和`b`，他们的乘积有系数`C[s] = sum A[i] * B[s-i]`。 

FFT 将两个数组变换到频域，其中卷积变成逐点乘法。 逆 FFT 将结果变换回来。 
6. 每次卷积后，将实值四舍五入到最接近的整数，然后对它们进行模减`997`。 

卷积前的系数很小，最多`996`，因此标准双精度复数 FFT 对于所需的模量来说足够准确。 官方的解决方案使用了异常小的模数`997`正是因为这个原因。 
7. 将每个所得多项式截断为次数`S`。 

一旦系数的度数大于最大查询，后面的乘法就无法将其降低，因为所有商品价格都是正数。 保留它只会增加 FFT 大小和运行时间。 
8. 通过直接读取目标度数的系数来回答每个查询。 

系数为`x^X`在`P(x)^k`是有序长度的数量-`k`选择总计`X`美分，所以这正是所要求的答案模数`997`。 

### 为什么它有效

 频率多项式对于每个可能的项目选择都有一项，其系数等于具有该价格的项目索引的数量。 在`P(x)^k`，从每一项中选择一项`k`副本对应于为狂欢的每个位置选择一个项目索引。 指数是它们价格的总和，而系数的乘积则计算产生相同价格序列的所有指数选择。 因此系数为`x^X`正是有效疯狂购物的总数`X`美分。 FFT计算与普通卷积相同的多项式乘积，二进制求幂计算完全相同`k`-次方作为重复乘法。 截断不能删除稍后可能对查询有贡献的系数，因为每个价格都是正数。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

MOD = 997
PI2 = 2.0 * math.pi

def fft(a, invert):
    n = len(a)

    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            a[i], a[j] = a[j], a[i]

    length = 2
    while length <= n:
        angle = PI2 / length
        if invert:
            angle = -angle
        wlen = complex(math.cos(angle), math.sin(angle))

        half = length >> 1
        for i in range(0, n, length):
            w = 1.0 + 0.0j
            end = i + half
            j = i
            while j < end:
                u = a[j]
                v = a[j + half] * w
                a[j] = u + v
                a[j + half] = u - v
                w *= wlen
                j += 1

        length <<= 1

    if invert:
        inv_n = 1.0 / n
        for i in range(n):
            a[i] *= inv_n

def convolution(a, b, limit):
    if not a or not b:
        return []

    need = min(len(a) + len(b) - 1, limit + 1)

    if len(a) == 1:
        x = a[0]
        return [(x * y) % MOD for y in b[:need]]

    if len(b) == 1:
        x = b[0]
        return [(x * y) % MOD for y in a[:need]]

    full = len(a) + len(b) - 1
    size = 1
    while size < full:
        size <<= 1

    fa = [complex(x, 0.0) for x in a]
    fb = [complex(x, 0.0) for x in b]

    fft(fa, False)
    fft(fb, False)

    for i in range(size):
        fa[i] *= fb[i]

    fft(fa, True)

    res = [0] * need
    for i in range(need):
        x = int(round(fa[i].real))
        res[i] = x % MOD

    return res

def poly_pow(base, exponent, limit):
    result = [1]

    while exponent:
        if exponent & 1:
            result = convolution(result, base, limit)

        exponent >>= 1
        if exponent:
            base = convolution(base, base, limit)

    return result

def parse_cents(s):
    if '.' in s:
        whole, frac = s.split('.')
        frac = (frac + '00')[:2]
    else:
        whole, frac = s, '00'
    return int(whole) * 100 + int(frac)

def solve():
    t = int(input())
    output = []

    for _ in range(t):
        n = int(input())

        prices = [parse_cents(input().strip()) for _ in range(n)]

        k, q = map(int, input().split())
        queries = [parse_cents(input().strip()) for _ in range(q)]

        limit = max(queries)

        base = [0] * (limit + 1)

        for price in prices:
            if price <= limit:
                base[price] += 1

        for i in range(len(base)):
            base[i] %= MOD

        if k == 0:
            answers = [1 if x == 0 else 0 for x in queries]
        else:
            result = poly_pow(base, k, limit)
            answers = [
                result[x] if x < len(result) else 0
                for x in queries
            ]

        output.extend(map(str, answers))

    sys.stdout.write("\n".join(output))

if __name__ == "__main__":
    solve()
```输入解析器有意处理字符串。`parse_cents`将十进制表示直接转换为整数，从而避免了 FFT 之前的所有浮点问题。 

这`base`array 是第一个算法步骤的多项式。 它的指数是以美分为单位的价格，其值是具有该价格的项目指数的数量。 大于最大查询的价格可以立即被忽略，因为每个价格都是正数。 

这`convolution`函数选择能够容纳完整卷积的最小二次方 FFT 大小。 然后将所得多项式截断为`limit + 1`。 截断是在逆 FFT 之后完成的，因为超出要求范围的系数可以简单地丢弃。 

对长度为 1 的多项式的特殊处理完全避免了 FFT。 这在二进制求幂期间很重要，因为中间多项式可能变得非常小，特别是当请求的范围很小或输入仅包含一个相关价格时。 

迭代 FFT 使用标准位反转排列，后跟蝶形层。 逆变换改变旋转角度的符号并将每个系数除以变换大小。 舍入与`int(round(...))`将每个整数系数周围的微小浮点误差转换回其预期的整数值。 

Python 整数不会溢出，因此在 C 或 C++ 中没有类似的固定宽度溢出问题。 FFT 本身使用 Python 复数，其实部和虚部都是双精度的。 由于系数减少了模数`997`每次乘法之后，它们对于预期的数值方法来说仍然足够小。 

求幂循环使用标准的最低有效位测试。 仅当剩余另一个求幂迭代时才执行平方，从而避免不必要的最终卷积。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(S log S log k)`| 每个多项式乘法都使用一个FFT卷积，并且需要进行二进制求幂`O(log k)`乘法|

对于十进制解析，输入例如`0.01`必须变成整数`1`， 尽管`1.10`必须成为`110`。 该解决方案解析小数点周围的字符，而不是评估浮点数。 这可以防止表示错误将有效的数组索引变成不正确的索引。 

对于模行为，多项式系数在每次乘法后都会减少。 由于所需答案是模数`997`，替换每个系数`c`经过`c mod 997`在下一次乘法之前保留每个后面的系数模`997`。 这也使 FFT 舍入误差保持较小，因为变换后的输入系数不会随指数增长。
