 ## 解决方案
 ## 问题理解

 光盘包含`t`曲目编号自`1`通过`t`，循环排列。 Anya 指定了必须完全按照该顺序播放的曲目序列。 第一个请求的曲目已被提示，因此无需按下任何按钮。 经过一段曲目后`k`结束后，玩家自然排队`k + 1`，包裹自`t`回到`1`。 

Arup 可以使用两个按钮更改排队的曲目。 向前按将排队的曲目前进一位，而向后按则将其后退一位。 由于轨道形成一个圆圈，因此每对连续请求的轨道之间的目标只是选择围绕该圆圈的较短方向。 输出是所有连续转换所需的最少按钮按下次数的总和。 原始竞赛声明指定`t <= 10^9`并且至多`1000`每个测试用例请求的轨道。 

大的界限`t`是关键约束。 一张 CD 可以包含 10 亿首曲目，因此模拟单个按钮按下可能需要数亿次操作才能实现单次转换。 由于请求的曲目多达 1000 个，这样的模拟可以达到大约`1000 * 5 * 10^8`，或关于`5 * 10^11`最坏情况下的按钮级操作。 每对请求的轨道都需要进行恒定时间计算。 测试用例的数量不受语句中较大值的限制，但总输入本身足够小，因此`O(s)`每个案例的解决方案很容易合适。 

第一个微妙的情况是请求的曲目正是自然播放的曲目。 例如：```
1
5 2
3 4
```正确的输出是：```
0
```跟踪后`3`完成、跟踪`4`已经在排队了。 粗心的实现可能会将当前位置视为轨道`3`并计算距离`1`，忘记了在按下任何按钮之前 CD 已经自然前进。 

第二个微妙的情况是围绕 CD 的末尾。 例如：```
1
5 2
5 1
```正确的输出是：```
0
```追踪`1`自然地遵循轨道`5`，所以不需要按钮。 使用普通绝对差的实现`5`和`1`会错误地获得`4`。 

第三种微妙的情况是连续两次请求同一曲目。 例如：```
1
3 3
3 1 1
```正确的输出是：```
1
```跟踪后`1`完成、跟踪`2`正在排队。 向后按一下即可返回曲目`1`。 简单地比较两个请求的轨道编号将给出距离零，这是错误的，因为自然过渡已经使玩家向前移动。 这个确切的案例是第三个官方样本。 

## 方法

 直接的暴力解决方案可以从字面上模拟 CD 播放器。 每个请求的曲目完成后，我们从自然排队的下一个曲目开始，并重复按前进或后退按钮，直到到达所需的曲目。 我们可以尝试两个方向并计算按压次数，然后选择较小的计数。 

这种方法是正确的，因为每次按下按钮都会将排队的曲目更改为圆形 CD 周围的一个位置。 然而，它完全忽略了 CD 最多可以包含 10 亿首曲目的事实。 在最坏的情况下，到达请求的轨道可能需要大约`t / 2`， 或者`5 * 10^8`，按下。 大约有 1000 个请求的曲目，这接近于`5 * 10^11`模拟操作，远远超出一秒竞赛限制。 竞赛评审明确指出，CD 最多可以有 10 亿首曲目，并且计算单个转换是不可行的。 

消除模拟的观察结果是，每个转变都发生在同一个圆形结构上。 假设之前请求的曲目是`a`。 一次`a`完成后，玩家已经在排队了```
a + 1
```和`t + 1`解释为`1`。 从排队的轨道开始，向前或向后移动只是在一个长度周期上的移动`t`。 

令排队轨道为`cur`和请求的目的地是`b`。 直接距离是`abs(cur - b)`。 向相反方向移动会穿过环绕线，因此需要`t - abs(cur - b)`按下。 最佳数量是这两个值中较小的一个。 

这减少了从潜在的数亿次模拟按压到少量算术运算的每次转换。 整个问题变成了对所请求序列的单次传递。 官方比赛评论描述了同样的减少，强调必须使用前一首歌曲结束后排队的曲目作为起点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(s * t)`最坏的情况|`O(1)`| 太慢了 |
 | 最佳|`O(s)`|`O(1)`| 已接受 |

 ## 算法演练

 1.读取曲目数`t`和所要求的顺序。 第一个请求的曲目不需要按下按钮，因为玩家最初会被提示到它。 
2. 将第一个请求的曲目设置为上一个曲目。 以后的每个转换都将相对于该值进行计算。 
3. 对于每个下一个请求的曲目`target`，计算自然会排队的曲目`previous`完成。 使用基于一的曲目编号，这是`(previous % t) + 1`。 

此步骤自动处理环绕。 如果`previous == t`，表达式产生`1`，完全匹配 CD 的循环行为。 
4. 计算自然排队轨道与`target`:```
direct = abs(current - target)
```5. 计算相反方向的距离：```
wrap = t - direct
```正好有`t`围绕整个周期的位置，因此移动后`direct`单向步骤，剩余路线包含`t - direct`步骤。 
6. 添加`min(direct, wrap)`到答案。 这是此转换所需的最少按钮按下次数。 
7. 更换`previous`和`target`并继续，直到处理完每个请求的曲目。 

### 为什么它有效

 不变量是在处理转换之前，`previous`是刚刚播放完的曲目。 最后，`(previous % t) + 1`正是无需按任何按钮即可排队的曲目。 从那时起，每个可能的按钮策略都是围绕长度周期移动`t`，因此当前轨迹和目标之间只有两个相关方向。 它们的长度是`direct`和`t - direct`，并且较短的一个是最佳的。 由于一旦知道其起始排队轨道，每个转换都是独立的，因此将这些最小转换成本相加即可得出全局最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    out = []

    for _ in range(n):
        t, s = map(int, input().split())
        tracks = list(map(int, input().split()))

        ans = 0
        previous = tracks[0]

        for target in tracks[1:]:
            current = previous % t + 1
            direct = abs(current - target)
            ans += min(direct, t - direct)
            previous = target

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```输入以测试用例的数量开始，与原始问题的格式相匹配。 然后，每个案例都会提供 CD 大小、请求的曲目数量以及请求的序列。 

第一个请求的曲目存储在`previous`并且对答案没有任何贡献。 这直接源于玩家已经被提示到该曲目的初始条件。 

对于以后的每首曲目，`previous % t + 1`计算自然排队的轨道。 这`% t`优于明确的`if previous == t`检查，因为它可以处理普通轨道和一个表达式的环绕。 

价值`direct`至多是`t - 1`， 所以`t - direct`始终是围绕圆另一侧的有效非负距离。 Python 整数具有任意精度，因此第二个官方示例的答案为`3000000000`requires no special integer type. 在具有固定宽度整数类型的语言中，应使用 64 位整数作为累积答案。 竞赛评审对可能超过 32 位整数的答案做出了相同的观察。 

操作顺序很重要。 在与目标进行比较之前，我们计算自然排队的轨道。 比较`previous`直接与`target`每一首完成的歌曲后都会错过自动单轨前进。

## 边缘情况

 对于自然后继情况，请考虑：```
1
5 2
3 4
```该算法开始于`previous = 3`。 它计算`current = 3 % 5 + 1 = 4`，已经等于目标。 因此`direct = 0`，并且过渡贡献为零。 最终输出是`0`。 这可以防止从轨道测量的常见错误`3`而不是来自已经排队的曲目`4`。 

对于环绕式，请考虑：```
1
5 2
5 1
```这里`previous = 5`， 所以`current = 5 % 5 + 1 = 1`。 目标也是`1`，成本为零。 CD 的循环排序直接由模表达式表示，因此最后一个轨道不需要特殊情况。 

对于重复请求，请考虑：```
1
3 3
3 1 1
```第一个过渡来自上一个轨道`3`到自然排队的轨道`1`，所以成本为零。 对于第二次转换，在轨道之后`1`完成、跟踪`2`正在排队。 目标是`1`， 所以`direct = 1`和相反的路线成本`3 - 1 = 2`。 算法选择`1`，产生正确的总数`1`。 这正是官方第三个样本所展示的行为。 

对于只有一首曲目的 CD，请考虑：```
1
1 1
1
```自然排队的曲目总是`1`。 直接距离为零，另一个距离为`1`，因此每次转换的成本为零。 如果只有一个请求的轨道，则根本没有过渡，并且答案也为零。 

对于半圆的情况，请考虑：```
1
10 2
1 7
```跟踪后`1`， 追踪`2`正在排队。 追踪`7`在十轨循环中，在任一方向上相距五个位置。 该算法计算`direct = 5`和`t - direct = 5`，然后选择`5`。 任一按钮方向都是最佳的，所以答案是`5`。
