 ## 解决方案
 ## 问题理解

 我们有一个由多行组成的文本文件。 对于每条线，只有它的长度很重要。 光标位置由行号和列号描述，其中第 0 列紧接在第一个字符和第一个列之前`s[i]`紧接在最后一个字符之后。 

可以使用四个箭头键移动光标。 左和右通常将列更改一，但在行边界处它们会跨入相邻行。 向上和向下更改行，同时尝试保留当前列。 如果目标行较短，则光标将被固定在该行的末尾。 在第一行或最后一行，尝试在文件外垂直移动没有任何效果。 

对于每种情况，我们都会得到行长度、当前光标位置和所需的光标位置。 我们需要按最少次数的箭头键才能到达所需位置。 

行数最多 120 行，每行最多 80 个字符。 因此，一条线最多有 81 个可能的光标列，包括两个端点。 整个文件最多有`120 * 81 = 9720`有效的光标状态。 该界限足够小，足以显式搜索状态空间。 探索所有状态且每个状态具有恒定数量的转换的解决方案对于一秒的限制来说很容易足够快。 相比之下，枚举可能的箭头键序列随着答案呈指数增长，即使移动几十次也变得毫无用处。 

错误的主要来源是将光标位置视为普通位置`(row, column)`移动不受限制的点。 有效列范围取决于行。 

例如，考虑```
2
1 0
1 0
2 0
```该文件有两行，第一行为空，第二行为空。 光标从第 1 行开头开始，需要到达第 2 行开头。答案是`1`，因为按一次向下键会直接移动到第 2 行。仅当当前列作为字符位置存在时才允许垂直移动的粗心实现可能会错误地拒绝移动，即使第 0 列在每一行上都有效。 

另一个边界情况是```
2
5 2
1 5
2 2
```答案是`1`。 光标位于第一行的末尾，按向下键将其移动到第二行的第 2 列，因为那里不存在第 5 列。 尝试在不进行钳位的情况下保留第 5 列的实现将创建无效状态。 

当水平跨线移动时，会出现不同的边界。 为了```
2
1 0
1 1
2 0
```答案是`1`。 光标位于第 1 行的末尾，因此向右将其移动到第 2 行的开头。独立处理每一行并拒绝跨换行会产生错误的答案。 

最后，尝试超越该文件不得创建新的状态。 为了```
1
5
1 0
1 5
```答案是`5`。 五次右按到达唯一一行的末尾。 第六次向右按下不执行任何操作，因此将无效按下视为有用转换的实现可能会错误地报告通过人工状态的较短路径。 

## 方法

 最直接的暴力想法是尝试所有可能的方向键序列，直到到达目标。 每个位置都有四个可能的按键，所以之后`k`最多可按`4^k`序列。 即使许多序列到达相同的光标位置，此方法也会单独探索这些重复。 有效状态的最大可能数量是 9720，因此原则上最短路径可以是数千步长。 枚举`4^9720`可能的序列是完全不可行的。 

这些重复序列之所以浪费，是因为光标的未来仅取决于其当前位置。 如果两个不同的按键序列达到相同的`(line, column)`，之后可能发生的一切都是相同的。 我们可以将这两种历史合并成一个状态。 

这一观察结果将编辑器变成了未加权的图表。 每个有效的光标位置都是一个顶点，按一个箭头键会创建一条到结果光标位置的边。 每条边只花费一次按键，因此广度优先搜索给出从当前位置到每个可到达位置的最短的按键次数。 

该图不需要显式构建。 对于每个状态，我们可以直接根据线路长度计算其四个邻居。 由于最多有 9720 个状态，每个状态最多有 4 个转换，因此 BFS 仅检查数万个转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(4^D)`在哪里`D`是最短路径长度|`O(D)`每个递归路径| 太慢了|
 | 最优 BFS |`O(F * 81)`|`O(F * 81)`| 已接受 |

 这里`F`是行数。 BFS 中的常数因子是四，因为每个光标状态都有四个可能的箭头键。 

## 算法演练

 1. 对待每个有效的光标位置`(r, c)`作为图状态。 对于线`r`，有效列是`0`通过`s[r]`，包含在内。 此表示自动处理空行，因为空行仅具有单个有效位置`(r, 0)`。 
2. 在当前光标位置启动 BFS 并将其指定为距离零。 状态的距离表示达到该状态所需的最少按键次数。 
3. 对于左移，如果`c > 0`，下一个状态是`(r, c - 1)`。 如果`c == 0`和`r > 0`，光标越过换行符并移动到`(r - 1, s[r - 1])`。 在第一行，Left 没有任何作用。 
4. 对于正确的移动，如果`c < s[r]`，下一个状态是`(r, c + 1)`。 如果`c == s[r]`和`r + 1 < F`，光标越过换行符并移动到`(r + 1, 0)`。 在最后一行，Right 没有任何作用。 
5. 对于向上移动，如果`r > 0`，移至上一行并将列夹紧至其长度。 目的地是`(r - 1, min(c, s[r - 1]))`。 如果光标已经在第一行，则向上键不起作用。 
6. 对于向下移动，如果`r + 1 < F`，移动到下一行并以相同的方式夹紧列，给出`(r + 1, min(c, s[r + 1]))`。 如果光标已经在最后一行，则向下键不起作用。 
7. 每当有效邻居未被访问时，为其分配比当前状态大一的距离，并将其放入 BFS 队列中。 我们第一次访问一个状态是它的最短距离，因为每条边的成本都是一。 
8. 当到达所需的光标位置时停止，或者根据需要让 BFS 完成。 为目标存储的距离是所需的最小按键次数。 

### 为什么它有效

 不变的是，当从 BFS 队列中删除某个状态时，其存储的距离是到达该光标位置所需的最小可能按键次数。 最初，对于距离为零的起始位置来说，这是正确的。 每个转换都代表一次合法的箭头键按下，因此新发现的状态接收的距离比到其前任的最短路径大一。 BFS 按非递减距离顺序处理状态，因此在第一次访问某个状态时，不可能有更短的未发现路径。 由于每个合法的光标移动都由四个生成的转换之一表示，因此通过编辑器的每个可能的路径都存在于图中。 因此，目标的 BFS 距离恰好是最小按键次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())

    for _ in range(n):
        f = int(input())
        length = list(map(int, input().split()))

        rc, cc = map(int, input().split())
        rm, cm = map(int, input().split())

        rc -= 1
        rm -= 1

        dist = [[-1] * (length[r] + 1) for r in range(f)]
        q = deque()

        dist[rc][cc] = 0
        q.append((rc, cc))

        while q:
            r, c = q.popleft()
            d = dist[r][c]

            if r == rm and c == cm:
                print(d)
                break

            # Left
            if c > 0:
                nr, nc = r, c - 1
                if dist[nr][nc] == -1:
                    dist[nr][nc] = d + 1
                    q.append((nr, nc))
            elif r > 0:
                nr, nc = r - 1, length[r - 1]
                if dist[nr][nc] == -1:
                    dist[nr][nc] = d + 1
                    q.append((nr, nc))

            # Right
            if c < length[r]:
                nr, nc = r, c + 1
                if dist[nr][nc] == -1:
                    dist[nr][nc] = d + 1
                    q.append((nr, nc))
            elif r + 1 < f:
                nr, nc = r + 1, 0
                if dist[nr][nc] == -1:
                    dist[nr][nc] = d + 1
                    q.append((nr, nc))

            # Up
            if r > 0:
                nr, nc = r - 1, min(c, length[r - 1])
                if dist[nr][nc] == -1:
                    dist[nr][nc] = d + 1
                    q.append((nr, nc))

            # Down
            if r + 1 < f:
                nr, nc = r + 1, min(c, length[r + 1])
                if dist[nr][nc] == -1:
                    dist[nr][nc] = d + 1
                    q.append((nr, nc))

if __name__ == "__main__":
    solve()
```输入以独立编辑器场景的数量开始。 然后，每个场景都会提供行数、每行的长度以及两个光标位置。 输入使用从一开始的行号，因此实现会立即将它们转换为从零开始的索引。 

这`dist`结构的每一行都有不同的长度。 对于一段长度的线`s`，正好有`s + 1`有效的光标位置。 这比分配固定的 81 列数组更好，因为它使得无效位置不可能意外地入队。 

四个过渡部分实现了编辑器的精确移动规则。 水平移动需要在零列和行尾处进行特殊处理，因为这些是左和右交叉换行符的点。 垂直运动用途`min(c, length[nr])`，它实现了编辑器的光标移动到较短行末尾的规则。 

条件`dist[nr][nc] == -1`有两个目的。 它标记某个状态是否已被访问，并防止 BFS 重复处理同一光标位置。 由于所有转换都有单位成本，因此分配给状态的第一个距离已经是最佳的。 

从队列中删除状态后立即检查目标。 BFS 以距离递增的顺序处理状态，因此一旦目标被弹出，它的距离就是答案。 该代码也可以继续执行，直到队列为空，但提前停止可以避免不必要的工作。 

Python 整数在这里不存在固定宽度溢出问题。 更重要的是，最大有用距离受有效状态数减一的限制，这与 Python 的整数范围相比很小。 

## 工作示例

 ### 示例 1

 第一个场景有七行，长度为`39, 20, 57, 54, 14, 38, 31`。 光标开始于`(7, 31)`，最后一行的末尾，并且必须到达`(3, 39)`，第 3 行末尾。 

一条最短路径具有以下 BFS 相关状态：

 | 步骤| 线路| 专栏 | 距离 | 移动|
 | ---| ---| ---| ---| ---|
 | 0 | 7 | 31 | 0 | 开始|
 | 1 | 6 | 31 | 1 | 上 |
 | 2 | 5 | 14 | 14 2 | 向上，夹紧|
 | 3 | 4 | 14 | 14 3 | 上 |
 | 4 | 3 | 14 | 14 4 | 上 |
 | 5 | 3 | 15 | 15 5 | 对|
 | 6 | 3 | 16 | 16 6 | 对|
 | ... | ... | ... | ... | ... |
 | 21 | 21 3 | 39 | 39 21 | 21 对|

 有趣的过渡是从第 6 行第 31 列到第 5 行。由于第 5 行只有 14 个字符，因此 Up 无法保留第 31 列。它会落在第 14 列。 从那里，光标可以继续向上，然后水平移动。 

答案是`21`，匹配示例输出。 这说明了为什么垂直运动不能简单地建模`(r - 1, c)`。 目标列必须限制为目标行的长度。 

### 示例 2

 第二种情况有线路长度`15, 30, 20`。 光标开始于`(1, 12)`并想要达到`(3, 3)`。 

| 步骤| 线路| 专栏 | 距离 | 移动|
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 12 | 12 0 | 开始|
 | 1 | 2 | 12 | 12 1 | 向下|
 | 2 | 3 | 12 | 12 2 | 向下|
 | 3 | 3 | 11 | 11 3 | 左|
 | 4 | 3 | 10 | 10 4 | 左|
 | 5 | 3 | 9 | 5 | 左|
 | 6 | 3 | 8 | 6 | 左|
 | 7 | 3 | 7 | 7 | 左|
 | 8 | 3 | 6 | 8 | 左|
 | 9 | 3 | 5 | 9 | 左|
 | 10 | 10 3 | 4 | 10 | 10 左|
 | 11 | 11 3 | 3 | 11 | 11 左|

 该表显示了一条有效路线，但它不是最短路线，因为示例答案是`8`。 相反，最短路径利用以利用线长度的方式水平和垂直移动的能力。 BFS 不需要我们猜测那条路线。 它考虑距离增加的所有可达状态并发现远处的目标`8`。 

这正是诸如“始终向目标行移动”之类的贪婪规则可能失败的地方。 当在线之间移动时，有用的水平坐标可能会发生变化，因此局部有吸引力的移动不必属于全局最短路径。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(sum(s[i] + 1))`, 至多`O(F * 81)`| 每个有效的光标状态都会被访问一次，并且最多有四个转换 |
 | 空间|`O(sum(s[i] + 1))`, 至多`O(F * 81)`| 距离数组和BFS队列存储游标状态 |

 最多 120 行，每行最多 81 个光标位置，搜索最多包含 9720 个状态和少于 40,000 个生成的转换。 这完全符合 1 秒时间限制和 256 MB 内存限制。 

## 测试用例```python
import sys
import io
from collections import deque

def solve(inp: str) -> str:
    data = io.StringIO(inp)

    def read():
        return data.readline

    input = read
    n = int(input())
    out = []

    for _ in range(n):
        f = int(input())
        length = list(map(int, input().split()))

        rc, cc = map(int, input().split())
        rm, cm = map(int, input().split())

        rc -= 1
        rm -= 1

        dist = [[-1] * (length[r] + 1) for r in range(f)]
        q = deque([(rc, cc)])
        dist[rc][cc] = 0

        while q:
            r, c = q.popleft()
            d = dist[r][c]

            if r == rm and c == cm:
                out.append(str(d))
                break

            neighbors = []

            if c > 0:
                neighbors.append((r, c - 1))
            elif r > 0:
                neighbors.append((r - 1, length[r - 1]))

            if c < length[r]:
                neighbors.append((r, c + 1))
            elif r + 1 < f:
                neighbors.append((r + 1, 0))

            if r > 0:
                neighbors.append((r - 1, min(c, length[r - 1])))

            if r + 1 < f:
                neighbors.append((r + 1, min(c, length[r + 1])))

            for nr, nc in neighbors:
                if dist[nr][nc] == -1:
                    dist[nr][nc] = d + 1
                    q.append((nr, nc))

    return "\n".join(out) + "\n"

## 边缘情况

 空行仅由一个有效的光标位置（第 0 列）表示。考虑```
1
3
2 0 2
1 2
3 0
```光标从第 1 行末尾开始。按一下右键即可进入空行，位置为`(2,0)`，然后再按一次右键进入第 3 行的开头。输出为`2`。 水平转换规则自然地处理这个问题，因为空行的末尾和它的开头位置相同。 

较短的目标线需要夹紧。 为了```
1
2
5 2
1 5
2 2
```光标从第 1 行的第 5 列开始。Down 尝试保留第 5 列，但第 2 行在第 2 列结束，因此结果状态为`(2,2)`。 一键按下即可达到目标，产生`1`。 

水平跨越线边界是另一种特殊情况。 和```
1
2
1 0
1 1
2 0
```光标从第 1 行末尾开始。向右无法增加列，因为该行的长度为 1，因此它移动到`(2,0)`反而。 答案是`1`。 

在文件的外部边界，箭头不起作用。 为了```
1
1
5
1 0
1 5
```BFS 可以通过五次右推到达目标。 一旦光标位于`(1,5)`，再次按右键不会创建新位置，因为没有下一行。 该实现根本不会生成不存在的转换。 

最微妙的边缘情况是最短路线不必看起来很贪婪。 在具有线长度的示例中`39, 20, 57, 54, 14, 38, 31`，即使当前列不存在于下一行，最短路径也会从垂直移动中受益，因为光标被固定在该行的末尾。 始终减小当前行或目标行或列之间的差异的策略可能会错过此类路线。 BFS 通过根据实际按键次数比较所有可到达的状态，完全避免了这种假设。
