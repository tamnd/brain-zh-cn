 ## 解决方案
 ## 问题理解

 这个问题要求我们研究一个道路网络，其中每个城市都有一个能源价值。 从一个城市出发，我们可以沿着道路行驶，但只允许进入能量不大于起始城市能量的城市。 对于每个城市，我们需要找出根据这条规则可以到达多少个城市。 任务来自Codeforces Gym 105979，Problem D。 

输入描述了一个无向图。 第一部分给出了城市和道路的数量，下一部分给出了每个城市的能量，其余的线描述了连接城市对的道路。 输出包含每个城市的一个值，表示该城市能源限制的可到达区域的大小。 

大界限是选择正确方向的关键。 该图最多可以包含一百万个城市和一百万条道路，因此从每个城市执行图搜索的解决方案在最坏的情况下大约需要 O(N(N+M)) 工作。 对于一百万个节点，即使触及所有可能的重复遍历中的一小部分也是不可能的。 我们需要接近线性地处理整个图。 

一个常见的错误是认为，如果我们从一个具有大量能源价值的城市开始，我们以后就可以以某种方式扩展到更大的城市。 移动规则仅基于起始城市的值，因此允许的集合正是能量小于或等于该起始值的城市。 这创建了能量的自然排序。 

考虑一个图表，其中每个城市都是孤立的。```
3 0
5 5 5
```正确的输出是：```
1
1
1
```粗心的解决方案可能会将同等能源的城市组合在一起，并假设它们是相连的，因为它们的价值观相匹配。 等能量不会创造道路，因此连通性仍然仅取决于图的边。 

另一个边缘情况是能量不断增加的链：```
3 2
1 2 3
1 2
2 3
```正确的输出是：```
1
2
3
```第一个城市无法去任何地方，因为下一个城市具有更高的能量。 第二个城市可以到达第一个，第三个城市可以到达三个城市。 在连接所有相等或较低节点之前单独处理每个能量时进行回答的解决方案可能会导致此顺序错误。 

最后一个微妙的情况是多个城市具有相同的能量：```
4 2
5 5 5 10
1 2
2 3
```正确的输出是：```
3
3
3
4
```所有三个能源 5 城市均可同时使用。 如果我们逐个处理相同的能量并立即回答，第一个处理的城市可能会错误地只看到其最终组成部分的一部分。 

## 方法

 直接的方法是从每个城市进行图遍历。 对于选定的起始城市，我们会步行穿过邻近的道路，而拒绝进入能量值较大的城市。 这是正确的，因为遍历完全遵循移动规则。 但是，如果图很大，则相同的道路和城市会被访问多次。 在密集或高度连接的图中，从每个城市重复此操作可以达到大约 O(N(N+M)) 操作，这远远超出了输入大小所允许的范围。 

问题的结构为我们提供了一种扭转观点的方法。 不要问“这个城市能去哪里？”，而要问“当我们逐渐让城市变得可用时会发生什么？”。 按能源对城市进行排序。 当我们按照能量从最小到最大的顺序处理城市时，当我们将所有城市激活到某个能量值x后，激活的城市之间的连通分量正是能量为x的城市可以探索的区域。 

这样做的原因是，每次允许的移动只会进入能量最多为起始值的城市。 如果我们按升序激活城市，则两个已激活城市之间的每条道路都代表当前能量限制内可能的运动。 不相交集并集结构可以在添加道路时维护这些连接的组件。 

重要的细节是处理相等的能量。 所有具有相同能量的城市必须一起激活，然后它们中的任何一个才能收到答案。 否则，通过其他相同能源城市的路径连接的两个相同能源城市可能还没有合并。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N(N+M)) | O(N(N+M)) | O(N+M) | 太慢了 |
 | 最佳| O((N+M) log N) | O((N+M) log N) | O(N+M) | 已接受 |

 ## 算法演练

 1. 按能源价值对所有城市进行排序。 我们将从最低能量到最高能量处理它们，因为能量为 x 的城市只关心在此排序中不晚于 x 出现的城市。 
2. 创建不相交集并集结构。 最初没有城市处于活动状态，因此每个组件都是空的。 该结构将存储哪些活跃城市已连接以及每个连接组件的大小。 
3. 对于能量相同的每组城市，先激活所有城市。 将一个城市标记为活跃意味着它现在可以参与具有这种能量或任何更大能量的城市的路径。 
4. 对于每个新激活的城市，检查所有相邻城市。 如果邻居已经处于活动状态，则合并两个组件。 该道路可用，因为两个端点都满足当前的能量限制。 
5. 当所有具有该能量的城市都被激活并合并后，为组中的每个城市分配组件大小。 该值是可到达的城市数量。 
6. 按照原城市顺序输出存储的答案。 

为什么它有效：

 不变量是，完成一组能量值x后，不相交集的并集分量恰好包含能量至多为x的城市所形成的子图的连通分量。 具有能量 x 的城市的每条可能的有效路径都必须位于该子图内，因此其分量的大小正是答案。 批量处理相同的能量可以保留不变量，因为具有相同限制的所有城市同时变得可用。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    energy = list(map(int, input().split()))

    graph = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    parent = list(range(n))
    size = [1] * n
    active = [False] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a = find(a)
        b = find(b)
        if a == b:
            return
        if size[a] < size[b]:
            a, b = b, a
        parent[b] = a
        size[a] += size[b]

    order = list(range(n))
    order.sort(key=lambda x: energy[x])

    ans = [0] * n
    i = 0

    while i < n:
        j = i
        value = energy[order[i]]
        while j < n and energy[order[j]] == value:
            j += 1

        for k in range(i, j):
            u = order[k]
            active[u] = True

        for k in range(i, j):
            u = order[k]
            for v in graph[u]:
                if active[v]:
                    union(u, v)

        for k in range(i, j):
            u = order[k]
            ans[u] = size[find(u)]

        i = j

    sys.stdout.write("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```代码首先使用邻接列表存储图，因为道路数量可能很大，我们需要有效地扫描邻居。 

不相交集并集实现使用路径压缩和按大小并集。 这些优化使每个合并操作的时间几乎恒定，当图表包含大约一百万条道路时，这是必要的。 

排序步骤创建可用城市的顺序。 主循环通过相等的能量组前进。 每个组内的两个单独的循环是必要的：首先组中的每个城市都变得活跃，然后考虑所有道路。 在同一通道中激活和合并会产生与前面描述的相同的相等能量错误。 

答案是在所有合并完成后从根存储的组件大小中获取的。 这`find`需要调用，因为在之前的工会之后，城市本身可能不再是根。

 ## 边缘情况

 对于孤立城市的情况：```
3 0
5 5 5
```该算法激活每个城市，但由于没有道路，因此不会发生联合操作。 每个 DSU 组件保持大小为 1，因此输出为`1 1 1`。 该方法从不假设相同的能量会产生连通性。 

对于递增链：```
3 2
1 2 3
1 2
2 3
```能源为 1 的城市首先被处理并形成尺寸 1 的组成部分。 当能源 2 被处理时，城市 2 变得活跃并与城市 1 合并，产生规模 2。 最后，城市 3 加入活跃组件，产生尺寸 3。 这完全遵循可达集。 

对于能量相等的情况：```
4 2
5 5 5 10
1 2
2 3
```在写入任何答案之前，前三个城市会一起激活。 这两条道路将它们合并为 3 级的一个组成部分，因此每个能源 5 城市都会收到正确的值。 最后一个城市稍后被激活，有足够的能量来查看之前的所有城市，因此它的尺寸为四。 这种情况破坏了一次处理一个相同能量的实现。
