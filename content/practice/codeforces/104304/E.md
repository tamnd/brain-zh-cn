 ## 解决方案
 ## 问题理解

 我们在数轴上得到一组静态线段，每个线段在有界宇宙内都有整数端点$L$。 对于每个查询段$[l, r]$，我们想要找到给定索引中最小索引的段$n$完全包含查询段的段。 一段$[a, b]$对于查询有效$[l, r]$如果$a \le l \le r \le b$。 如果没有段包含查询，我们返回 0。 

该结构是不对称的：查询要求包含，而不是重叠，因此必须同时尊重两个端点。 这使得仅基于一个端点的天真排序技巧不够。 

约束达到$n, q, L \le 5 \cdot 10^5$。 这立即排除了任何扫描每个查询的所有段的解决方案，因为这将花费高达$2.5 \cdot 10^{11}$比较。 即使每个查询的对数因子也必须仔细设计，因为我们在所有维度上同时以 50 万规模进行操作。 任何更接近的解决方案$O(nq)$或者$O(n \log n)$预处理之后$O(n)$每个查询都会失败。 

一个微妙的困难是答案取决于最小的索引，而不是最紧或最小的段。 这打破了贪婪的几何直觉：如果存在稍小但索引较早的段，则具有大索引的非常大的段是无关紧要的。 

经常破坏简单解决方案的一种边缘情况是多个段共享相同的端点。 例如，段$[1, 10]$,$[1, 10]$， 和$[1, 10]$随着索引的增加和查询$[1, 10]$。 正确答案是索引 1，而不仅仅是任何匹配段，因此算法必须保留索引优先级，而不仅仅是可行性。 

另一种失败情况是位于极端边界的查询，例如$[L, L]$。 只有覆盖整个范围到正确端点的段才重要，因此依赖于部分扫描而没有适当结构的解决方案常常会错过它们。 

## 方法

 一种直接的方法是迭代每个查询的所有段并检查该段是否包含查询间隔。 这是正确的，因为遏制很容易通过两次比较来测试。 然而，每次查询的成本$O(n)$，导致$O(nq)$，在最大输入大小时速度太慢。 

关键的观察结果是，遏制可以分为两个独立的条件：$[a, b]$查询有效$[l, r]$当且仅当$a \le l$和$b \ge r$。 这表明二维优势关系：点$(a, b)$主导查询$(l, r)$如果它们同时位于西南和东北方向。 

对于每个查询点，我们需要满足两个不等式的所有点中的最小索引。 这是一个经典的二维离线优势查询问题，但附加了最小化索引的要求，这成为第三维。 

处理此问题的一种自然方法是处理按左端点分组的查询并维护右端点上的结构。 如果我们修复左阈值$l$，我们希望在所有细分中$a \le l$找到最小的索引，使得$b \ge r$。 这将问题简化为一组由右端点键入的动态段，其中我们必须支持对后缀的最小范围查询。 

我们可以扫描左端点从 1 到$L$，插入左端点变为活动状态的段。 对于每个可能的左值，我们在右端点上维护一个线段树，存储在当前扫描位置之前或开始的任何线段的最小索引。 左边的每个查询$l$然后变成查询范围内的最小索引$[r, L]$。 这将每个查询减少为单个线段树范围最小查询。 

这是有效的，因为扫描确保我们此时用左边界回答查询$l$，所有有效段$a \le l$已经插入。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nq)$|$O(1)$| 太慢了|
 | 扫描+线段树|$O((n+q)\log L)$|$O(L)$| 已接受 |

 ## 算法演练

 我们将每个段转换为其左端点的事件，并按其左端点对查询进行分组。 然后我们从左到右扫描所有位置。 

1. 按段的左端点创建一个段桶。 对于每个段$[a, b]$，将其索引存储在桶中$a$。 这确保了我们可以在段的左边界符合条件时准确地激活段。 
2. 还按其左端点创建查询存储桶。 每个查询存储$(r, id)$。 这允许回答当前满足左边界的所有查询。 
3. 在域上构建线段树$[1, L]$，其中每个位置对应一个右端点值。 每个节点存储当前与该右端点处于活动状态的任何段的最小索引。 最初，所有值都是无穷大或哨兵大数。 
4、扫一扫$l$从 1 到$L$。 在每个位置$l$，插入所有具有左端点的线段$l$通过更新位置进入线段树$b$有价值$i$。 这意味着该段$[l, b]$现在可用于任何左侧至少为$l$。 
5、插入后，处理左端点为的所有查询$l$。 对于查询$[l, r]$，我们需要在所有活跃段中具有$b \ge r$。 这正是线段树上区间最小范围查询$[r, L]$。 
6. 如果查询结果仍然是哨兵值，则输出0。否则输出找到的最小索引。 

正确性取决于以下事实：在扫描位置$l$，活动集恰好是最多具有左端点的所有线段$l$。 任何左端点大于的线段$l$尚未插入，因此它不会错误地影响早期的查询。 

## 为什么它有效

 在每个扫描位置$l$，数据结构准确地表示满足以下条件的段集$a \le l$。 如需查询$l$，任何有效段都必须属于该集合。 剩余约束$b \ge r$通过将线段树查询限制为后缀来强制执行$[r, L]$。 由于每个段在其左端点处只插入一次并且永远不会被删除，因此该结构保持了可行候选的单调扩展。 因此，范围查询中存储的最小索引是有效集合中的最小值，从而确保了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**18

class SegTree:
    def __init__(self, n):
        self.n = 1
        while self.n < n:
            self.n *= 2
        self.seg = [INF] * (2 * self.n)

    def update(self, i, v):
        i += self.n - 1
        if v < self.seg[i]:
            self.seg[i] = v
        else:
            self.seg[i] = v
        i //= 2
        while i:
            self.seg[i] = min(self.seg[2*i], self.seg[2*i+1])
            i //= 2

    def query(self, l, r):
        l += self.n - 1
        r += self.n - 1
        res = INF
        while l <= r:
            if l % 2 == 1:
                res = min(res, self.seg[l])
                l += 1
            if r % 2 == 0:
                res = min(res, self.seg[r])
                r -= 1
            l //= 2
            r //= 2
        return res

def solve():
    n, q, L = map(int, input().split())

    segs = [[] for _ in range(L + 2)]
    queries = [[] for _ in range(L + 2)]

    for i in range(1, n + 1):
        a, b = map(int, input().split())
        segs[a].append((b, i))

    for i in range(q):
        l, r = map(int, input().split())
        queries[l].append((r, i))

    st = SegTree(L)
    ans = [0] * q

    for l in range(1, L + 1):
        for b, idx in segs[l]:
            st.update(b, idx)

        for r, qi in queries[l]:
            res = st.query(r, L)
            ans[qi] = 0 if res == INF else res

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```线段树构建在右端点域上，以便后缀查询变得高效。 每次更新都会在位置写入段索引$b$，确保所有段结束于或超出$r$在查询期间会被考虑。 

一个微妙的点是我们存储每个右端点位置的最小索引。 即使多个段共享相同的$b$，只保留最小的索引，因为问题需要整体最小的索引。 

## 工作示例

 考虑一个带有段的小实例$[1, 6]$,$[1, 4]$， 和$[4, 5]$，和查询$[2, 4]$和$[3, 5]$。 

我们从左到右扫描并保持活动段。 

| 我| 插入段| 活性结构 (b:min idx) | 查询 | 结果|
 | --- | --- | --- | --- | --- |
 | 1 | (1,6),(1,4) | (1,6),(1,4) | b=4:2，b=6:1 | - | - |
 | 2 | 无 | 相同| (2,4) | 2 |
 | 3 | 无 | 相同| (3,5) | 1 |
 | 4 | (4,5) | b=4:2，b=5:3，b=6:1 | - | - |
 | 5 | 无 | 相同| - | - |

 查询时$[2,4]$，我们取后缀$b \ge 4$，给出索引 {2,1} 并选择 2。在查询时$[3,5]$， 后缀$b \ge 5$给出 {1,3}，所以答案是 1。 

该跟踪表明，左边界的早期激活正确捕获了所有候选者，而后缀查询则强制执行右边界。

 ## 边缘情况

 一种边缘情况是多个段共享相同的右端点但索引不同。 例如，段$[1, 5]$,$[2, 5]$,$[3, 5]$，和一个查询$[2, 5]$。 在插入过程中，所有三个都映射到位置$b=5$。 线段树更新确保存储最小索引，因此位置5保存索引1。用于查询$[2, 5]$， 后缀$[5, L]$仅包含该位置，因此答案正确为 1。 

另一种情况是当查询左边界很大时，比如$[L, L]$。 仅具有左端点的线段$L$是在那时插入的。 如果不存在具有足够右端点的线段树，则线段树返回无穷大并且算法输出 0。这避免了不满足左约束的早期线段的误报。
