 ## 解决方案
 ## 问题理解

 我们得到一个排列在圆圈上的二进制序列。 每个位置包含 0 或 1，并且索引环绕，以便位置 n−1 与位置 0 相邻。允许的操作选择任何起始索引 b 并恰好翻转该圆上的 k 个连续位置，这意味着每个选定的位从 0 反转到 1 或从 1 反转到 0。 

目标是使用尽可能少的次数的长度为 k 的圆形翻转将整个圆变成全圆，并且如果可能的话，还输出一个最佳的操作序列。 如果根本无法做到，我们必须报告不可能。 

关键约束是所有测试用例的 n 之和最多为 2×10^6。 这迫使每个测试用例的任何解决方案都是线性的，因为当 T 很大时，即使每个测试的 O(n log n) 也会太慢。 内存使用也必须是线性的并仔细管理。 

一个微妙的困难来自于圆形结构。 许多简单的解决方案将数组视为线性并忽略环绕效应。 这会破坏正确性，因为接近结束的操作会影响开始。 另一个常见的陷阱是贪婪翻转而没有正确跟踪奇偶校验，这会导致关于可行性的错误结论。 

一个小的说明性失败案例是 n=5、k=2、a=[1,0,0,0,1]。 线性化数组上的天真从左到右贪婪可能会修复早期的零，但忘记最后的翻转会再次影响索引 0，即使存在有效的循环策略，也会产生不一致的最终状态。 

## 方法

 蛮力的观点很简单：我们模拟选择操作的过程并尝试最小化它们的数量。 在每一步中，我们可以选择任何索引作为起点，应用翻转，然后继续递归。 这在大小为 2^n 的状态图上形成了一个最短路径问题，即使对于 n=20，这也是完全不可行的，因为每个状态都有 n 个转换，并且状态空间呈指数爆炸。 

关键的结构是翻转 k 个连续位置可以建模为切换滑动窗口奇偶校验效应。 我们不是动态跟踪完整的配置，而是在考虑之前的操作后跟踪每个位置当前是否正确或不正确。 如果我们按顺序扫描，一旦我们决定当前位置必须固定，每个操作选择都会被强制。 

主要障碍是循环性。 为了消除它，我们观察到圆上的任何有效解决方案都可以通过仔细考虑前 k−1 个位置并确保环绕时的一致性来表示。 标准技巧是线性处理序列，但强制翻转超出 n 换行并影响前缀位置，这可以通过模块化索引处理，同时维护差异数组。 

我们维护一个差异数组，跟踪有多少活动翻转影响每个位置模 2。当我们从 0 扫描到 n−1 时，我们通过维护运行奇偶校验来知道当前位是否被翻转。 如果在应用先前的操作后当前位为 0，我们将被迫在该位置开始翻转，因为未来的操作无法在不影响之前固定位置的情况下追溯更改它。 

在位置 i，我们决定是否应用从 i 开始的操作。 如果这样做，我们将使用差分结构切换范围 [i, i+k) 模 n 的奇偶校验。 唯一的复杂之处是确保我们不超过 n 次操作的限制，并且在操作回绕时保持一致。 

贪婪之所以有效，是因为每个位置最后都必须为 1，而在位置 i 处固定 0 的唯一方法是从 i 或更早的位置开始应用翻转，但仍覆盖它。 一旦我们通过了 i，未来的操作就无法在不违反先前决策的情况下覆盖 i，因此该选择是本地强制的。

 | --- | --- | --- | --- |
 | 暴力搜索 | O(2^n·n) | O(2^n·n) | O(2^n) | O(2^n) | 太慢了 |
 | 差值数组贪婪扫描 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们首先将问题转化为跟踪翻转如何影响每个位置。 每个操作都会在一个圆上切换长度为 k 的连续段，因此我们使用支持范围异或更新的差异数组来模拟效果。 

我们维护一个运行变量 current_flip_parity ，它告诉我们当前位置是否已翻转奇数次。 

我们还维护一个大小为 n+1（逻辑循环）的数组 diff，以有效地应用范围切换。 

1. 用零初始化 diff 数组，并且 current_flip_parity = 0。我们还为所选操作准备一个答案列表。 
2. 按顺序将 i 从 0 扫到 n−1。 在每个位置，通过添加 diff[i] 模 2 来更新 current_flip_parity。这告诉我们 a[i] 当前是否反转。 
3. 计算有效值：如果current_flip_parity为1，则该位被翻转，否则为原始位。 如果有效值为 1，我们继续前进，因为该位置已经满足目标。 
4. 如果有效值为 0，我们必须从 i 开始执行操作。 我们将 i 记录为操作开始。 
5. 从 i 开始进行长度为 k 的翻转。 这是通过以循环方式更新 diff[i] 和 diff[i+k] (mod n) 来完成的。 如果该段回绕，我们将更新分为两个间隔。 
6. 相应地更新 current_flip_parity 并继续。 
7. 处理完所有索引后，验证在累积翻转下所有仓位是否都以 1 结尾。 如果不是，输出-1。 

它之所以有效，来自于强制选择不变量。 当我们到达位置 i 时，所有可能影响 i 但不触及较早索引的操作都已确定。 在 i 之后开始的任何操作都不能影响 i，因此如果 i 当前为 0，唯一可能的修复方法是在 i 处开始翻转。 这使得贪婪决策既必要又充分，并且差异数组确保我们一致地应用效果而无需重新计算段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    diff = [0] * (n + 1)
    cur = 0
    ops = []

    for i in range(n):
        cur ^= diff[i]

        if (a[i] ^ cur) == 0:
            ops.append(i)
            cur ^= 1

            end = i + k
            if end < n:
                diff[end] ^= 1
                if i + 1 <= n:
                    diff[i + 1] ^= 1
            else:
                end %= n
                diff[0] ^= 1
                if i + 1 <= n:
                    diff[i + 1] ^= 1

    check = 0
    diff2 = [0] * (n + 1)

    for i in range(n):
        check ^= diff2[i]
        if (a[i] ^ check) == 0:
            return "-1"

        if i in ops:
            check ^= 1
            end = i + k
            if end < n:
                diff2[end] ^= 1
                if i + 1 <= n:
                    diff2[i + 1] ^= 1
            else:
                end %= n
                diff2[0] ^= 1
                if i + 1 <= n:
                    diff2[i + 1] ^= 1

    out = [str(len(ops))]
    if ops:
        out.append(" ".join(map(str, ops)))
    else:
        out.append("")
    return "\n".join(out)

def main():
    t = int(input())
    for _ in range(t):
        print(solve())

if __name__ == "__main__":
    main()
```该实现在圆上维护一条扫描线，同时使用差异数组来模拟范围异或更新。 变量 cur 表示影响当前索引的活动翻转的奇偶校验。 当某个位置的值为 0 时，我们立即承诺从该位置开始翻转。 

由于循环引入了环绕，因此必要时会拆分更新。 第二遍验证正确性，确保不会因循环传播而留下隐藏的不一致。 

一个微妙的点是，我们将操作位置记录在一个列表中，并在验证过程中重放它们。 这避免了单独信任中间状态，中间状态在环绕逻辑下可能很脆弱。

 ## 边缘情况

 关键边缘情况是 k 接近 n 时。 在这种情况下，每次翻转几乎覆盖了整个圆圈，因此早期的贪婪决策强烈限制了后来的位置。 该算法可以处理此问题，因为每当位置为 0 时，扫描仍然会强制做出决策，并且环绕更新可确保跨边界的一致性。 

另一种边缘情况是数组已经全为 1 时。 该算法不执行任何操作，因为每一步都已满足每个有效值，因此 ops 保持为空并且输出正确返回 0 个操作。 

更微妙的情况是，由于 i+k 超过 n，操作会多次回绕。 分割更新确保前缀和后缀都正确切换，因此不会在圆形边界上累积隐藏的奇偶校验漂移。
