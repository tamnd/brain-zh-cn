 ## 解决方案
 ## 问题理解

 有`n`城市和`t`历史道路配置。 配置`i`准确地描述了那个历史时刻存在哪些双向道路。 在旅途中，时间机器将我们送入固定的序列`k`配置，`a_1, a_2, ..., a_k`。 每次跳跃后，我们要么留在当前城市，要么恰好穿越该配置中存在的一条道路。 

我们从城市开始`1`在第一次跳跃之前。 如果我们在这段时间内使用道路`i`第-次跳跃，我们在时间位置到达另一个端点`i`。 目标是到达城市`n`在尽可能小的位置`i`。 第一次跳跃很重要，所以到达城市`n`使用道路时`a_1`给出答案`1`。 如果城市`n`永远无法到达，答案是`-1`。 

相关界限是`n, t, k <= 2 * 10^5`，而所有历史配置的道路总数最多为`2 * 10^5`。 这排除了任何重复扫描所有道路以查找每个时间位置的情况。 单个配置可能包含`2 * 10^5`道路，可能会出现`2 * 10^5`位置，这已经产生`4 * 10^10`边缘检查。 一个算法围绕`O((n + m + k) log(n + k))`， 在哪里`m`是道路总数，是合适的。 

有两个微妙的计时细节经常会导致错误的解决方案。 首先，一条边不能在到达起始城市的同时使用，因为每次跳跃后只能穿过一条路。 例如：```
3 1
2
1 2
2 3
1
1
```答案是`-1`。 两条路同时存在`1`，但此时我们只能遍历其中一个。 搜索大于或等于当前时间的事件的解决方案将错误地获得`1`对于整个路径。 

其次，即使我们在任何列出的时间之前开始，第一次位置也必须被认为是可用的。 例如：```
2 1
1
1 2
1
1
```答案是`1`。 我们从城市开始`1`有效时间为`0`，所以出现在位置`1`是道路的第一个可用的出现点。 

第三种边缘情况是相同配置的重复出现可以被其他配置分开。 例如：```
3 1
1
1 3
3
1 1 1
```答案是`1`，因为第一次出现就已经足够了。 更一般地说，如果某个城市在以下位置可到达`2`，相同配置的道路不能在该位置再次使用`2`，但可以在下次出现时使用。 该算法必须保留这种严格的顺序。 

## 方法

 直接模拟会维护每次跳跃后可到达的城市集。 对于每次出现的配置`a_i`，我们检查其道路并标记当前可以到达其他端点的任何道路的端点。 这是正确的，因为此时可以使用一条道路，因此与当前可到达集合的图距离最多为 1 的顶点将变得可到达。 

问题是相同的配置可能会出现多次。 假设一个历史配置包含所有`2 * 10^5`允许的道路并且序列完全包含该配置`2 * 10^5`时间位置。 扫描每个位置的完整边缘集的成本高达`4 * 10^10`边缘检查。 这些限制旨在使这种方法变得不可能。 

有用的观察是，每条道路都属于一种历史配置，并且时刻的完整序列是预先已知的。 对于每个配置，我们可以存储它出现的位置。 现在考虑一条固定道路`(u, v)`属于配置`g`。 

假设我们最早可以到达城市的时间`u`是`d`。 我们不能在以下位置使用这条路`d`，因为达到`u`在位置`d`已经消耗了该位置可用的单一道路移动。 我们需要第一个位置严格大于`d`在哪种配置下`g`出现。 如果那个位置是`w`，那么我们可以从`u`到`v`恰好在时间`w`。 

这将每条普通道路变成了依赖于时间的过渡。 给定一个端点的当前最早到达时间，二分搜索会找到道路配置的最早合法出现。 一旦我们有了这样的转变，问题就具有与最短路径问题相同的结构：较早到达城市永远不会使后来的转变变得更糟，因此迪杰斯特拉算法适用。 

蛮力方法之所以有效，是因为它明确地模拟了每个历史时刻。 它会失败，因为相同的道路可能会被一次又一次地检查。 观察到每个边都可以查询其下一个可用的出现，这将重复模拟减少到每个边松弛一次二分搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(km)`在最坏的情况下|`O(n + m)`| 太慢了 |
 | 最佳 |`O(m log k + m log n + k)`|`O(n + m + k)`| 已接受 |

 这里`m`表示所有历史配置的道路总数。 

## 算法演练

 1. 读取每条道路并将其存储在一个普通的无向图中。 与每条边一起存储该道路存在的历史配置的标识符。 我们不需要保留单独的图，因为配置标识符足以确定何时可以使用边。 
2. 阅读顺序`k`历史配置。 对于每种配置`g`，存储包含所有位置的排序列表`i`为此`a_i = g`。 输入序列本身已经排序，因此这些列表自然排序。 
3. 定义`dist[v]`作为哪个城市的最早时间位置`v`可以到达。 最初`dist[1] = 0`,因为我们在城市`1`在第一次跳跃之前。 每隔一个距离都是无穷大。 
4. 放置城市`1`进入最小堆并运行 Dijkstra 算法。 当城市`u`以其当前最佳时间从堆中删除`dist[u]`，检查每条道路`(u, v)`其事件。 
5.假设道路`(u, v)`属于配置`g`。 查看已排序的位置列表，其中`g`出现并二分搜索第一个位置严格大于`dist[u]`。 这是我们到达后最早可以走这条路的时刻`u`。 
6. 如果该位置是`w`，那么我们可以达到`v`在某个时间`w`。 放松`dist[v]`和`w`。 如果`w`小于当前值`dist[v]`，将新的对插入堆中。 
7. 到达城市时停车`n`被从堆中删除，因为 Dijkstra 按照最终最短路径距离的非递减顺序删除顶点。 如果堆先变空，city`n`无法到达，答案是`-1`。 

关键的不变量是`dist[u]`是我们最早能到达城市的时间`u`。 对于属于配置的边`g`，每次合法遍历后到达`u`必须发生在发生`g`严格之后`dist[u]`。 二分搜索选择最早出现的此类事件，因此转换给出了通过该边最早可能到达另一个端点的信息。 然后 Dijkstra 按升序考虑这些最早的转移，就像对待普通非负最短路径一样。 由于每个转换都在时间上严格向前移动，因此任何转换都不能返回到较早的状态。 

## Python 解决方案```python
import sys
import heapq
from bisect import bisect_right

input = sys.stdin.readline

def solve():
    n, t = map(int, input().split())

    graph = [[] for _ in range(n)]

    for g in range(t):
        m = int(input())
        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            graph[u].append((v, g))
            graph[v].append((u, g))

    k = int(input())
    sequence = list(map(int, input().split()))

    occurrences = [[] for _ in range(t)]
    for i, g in enumerate(sequence, 1):
        occurrences[g - 1].append(i)

    INF = k + 1
    dist = [INF] * n
    dist[0] = 0

    pq = [(0, 0)]

    while pq:
        du, u = heapq.heappop(pq)

        if du != dist[u]:
            continue

        if u == n - 1:
            print(du)
            return

        for v, g in graph[u]:
            times = occurrences[g]

            # We must use the road at a strictly later time.
            pos = bisect_right(times, du)

            if pos == len(times):
                continue

            nd = times[pos]

            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    print(-1)

if __name__ == "__main__":
    solve()
```图结构将每条道路存储两次，一次来自每个端点，并记住其历史配置。 这会将原始图集合转换为边缘带有时间标签的稀疏图。 

在读取完整的时间序列后构建出现列表。 因为位置是从`1`通过`k`，每个列表都已排序并且可以使用以下命令进行搜索`bisect_right`。 

的选择`bisect_right(times, du)`是核心实施细节。`bisect_right`返回第一次出现的严格大于`du`。 使用`bisect_left`将允许在到达当前城市的同时遍历一条边，错误地允许在一次跳跃后遍历两次道路。 

堆存储`(time, city)`，因此首先处理已知的最小到达时间。 当陈旧的堆条目的存储时间不同于`dist[u]`，这是 Dijkstra 的标准延迟删除实现。 

所有时间最多为`k`， 所以`INF = k + 1`就足够了。 Python 整数不会溢出，但无论如何这里也不需要大的哨兵。 

早出城时`n`被弹出是安全的，因为 Dijkstra 的堆顺序保证了以后的松弛不会产生更小的到达该城市的时间。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(m log k + m log n + k)`| 每次 Dijkstra 提取都会检查每个有向边一次，并通过二分搜索找到其下一个可用的出现位置 |
 | 空间|`O(n + m + k)`| 图表存储`2m`有向边，而所有出现列表一起包含`k`职位 |

 和`m <= 2 * 10^5`,`k <= 2 * 10^5`， 和`n <= 2 * 10^5`，该算法仅对每个道路松弛执行对数工作，而不是针对每个时间位置重复扫描道路。 内存使用量与实际输入大小呈线性关系，完全符合 512 MB 的限制。

 ## 边缘情况

 第一个重要的边缘情况是第一次位置。 考虑：```
2 1
1
1 2
1
1
```该算法开始于`dist[1] = 0`。 配置的出现列表`1`是`[1]`。`bisect_right([1], 0)`回报指数`0`，所以道路可以在位置使用`1`和`dist[2]`变成`1`。 答案是正确的`1`。 

第二种边缘情况是一个历史配置中的多条道路。 考虑：```
3 1
2
1 2
2 3
1
1
```城市`1`可以到达城市`2`在某个时间`1`， 但`dist[2] = 1`意味着随后使用来自城市的道路`2`必须严格晚于时间发生`1`。 后面没有出现配置`1`，所以城市`3`仍然无法访问。 算法输出`-1`。 

第三种边缘情况是重复使用一种配置。 考虑：```
3 1
2
1 2
2 3
2
1 1
```从城市出发`1`，第一次出现到达城市`2`在某个时间`1`。 处理城市边缘时`2`到城市`3`,`bisect_right([1, 2], 1)`返回第二次出现的位置`2`。 因此`dist[3] = 2`，这正是最早的有效答案。 

第四种边缘情况是即使存在几条道路也无法到达目的地。 在第二个样本中，城市`4`达到时间`3`，但这是通往城市的唯一道路`5`属于配置`2`，其唯一出现的时间是`2`。 二分查找找不到严格大于的出现`3`，因此这种转变根本不存在。 Dijkstra 最终耗尽了所有可到达的城市和输出`-1`。 

所有这些情况背后的中心实现规则都是相同的：对于属于配置的道路`g`，每次到达一个端点后`d`，仅第一次出现`g`严格大于`d`是相关的。 一旦正确地表示了该转换，剩下的问题就是标准的最早到达最短路径计算。
