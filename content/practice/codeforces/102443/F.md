 ## 解决方案
 ## 问题理解

 正多边形的所有顶点围绕圆等距分布。 我们必须计算每个三角形，其三个顶点来自多边形并且其边长至少包含一对相等的对。 

关键的难点在于多边形最多可以有 10 9 个顶点。 显式检查顶点或三元组的方法行不通。 即使 O(n) 对于时间限制来说也已经太大了，因此预期的解决方案必须将答案减少到恒定数量的算术运算。 

还有一个微妙的计数问题。 如果我们选择一个顶点作为等腰三角形的顶点，则其他两个顶点可以对称地放置在该顶点周围。 这对每个普通的等腰三角形都计数一次，但等边三角形有三个可能的顶点，因此它会被计数三次。 我们必须准确纠正这种情况。 

例如，对于输入 3，多边形本身是一个等边三角形。 基于顶点的直接计数给出三，因为它的每个顶点都可以被选择作为顶点。 正确答案是 1，因此简单地计算对称对就会超出计算等边三角形。 

另一种边缘情况是均匀大小的多边形。 当n=4时，选择顶点两侧的相反顶点将选择相同的多边形顶点两次，因此该选择不会形成三角形。 正确答案是 4，而不是 8。这就是为什么有效对称距离的数量是 ⌊(n−1)/2⌋。 

对于n=6，等边三角形确实存在。 基于顶点的计数给出 6⋅2=12，但有 6/3=2 个不同的等边三角形，每个计数三次。 我们必须为每个等边三角形减去两个额外的计数，得到 12−2⋅2=8。

一种稍微好看一点的方法是修复一个顶点并尝试每一对剩余的顶点，但这仍然是 O(n 2 )，这对于 n=10 9 来说是不可能的。 

有用的结构来自正多边形。 固定顶点 v 作为顶点。 当另外两个顶点在相反方向上围绕多边形距离相等时，它们到 v 的距离恰好相等。 如果到一个端点的顺时针距离为 k，则到另一端点的逆时针距离也必须为 k。

### 为什么它有效

 对于每个选定的顶点，等腰三角形的等边必须将顶点连接到距其角距离相等的两个顶点。 由于所有多边形顶点的角度间隔相等，因此对于某个有效的 k，这两个顶点恰好是相反方向的 k 步。 因此，每个等腰三角形在我们的计数中至少有一种表示形式。 

非等边等腰三角形有唯一的顶点，因此只计算一次。 等边三角形有三个可能的顶点，因此被计数三次。 这些是唯一具有多个顶点表示的三角形，因此为每个等边三角形减去两个副本会使每个有效三角形仅计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    ans = n * ((n - 1) // 2)

    if n % 3 == 0:
        ans -= 2 * (n // 3)

    print(ans)

if __name__ == "__main__":
    solve()
```表达式`(n - 1) // 2`计算一个顶点的有效对称距离数。 使用`n - 1`而不是`n`当 n 为偶数时，会阻止在两侧选择相同的顶点。 

乘以`n`考虑到每一个可能的顶点。 Python 整数处理最大结果而不会溢出，这在这里很有用，因为答案可能约为 5⋅10 17，远远超出 32 位有符号整数。 

可分性检查`n % 3 == 0`处理唯一的多算情况。 当它成立时，`n // 3`是不同等边三角形的数量，每个三角形都需要删除两个多余的副本。 

没有顶点循环，因此无论 n 是 3 还是 10 9，算法都只执行固定数量的算术运算。

 ## 边缘情况

 对于 n=3，该算法计算每个顶点的一个对称选择，得到 3。由于 3∣n，它减去 2(3/3)=2，产生 1。这处理了可能的最小多边形，并说明了为什么不能简单地忽略等边三角形。 

对于 n=4，算法计算每个顶点 ⌊3/2⌋=1 个对称选择，得到 4。没有等边校正，因为 4 不能被 3 整除。结果是 4，对应于从正方形中省略一个顶点得到的四个三角形。 地板操作至关重要，因为从顶点顺时针走两步和逆时针走两步会到达同一个相反的顶点。 

对于 n=6，每个顶点有两个对称选择，初始计数为 12。由于 6 可被 3 整除，因此有 6/3=2 个等边三角形。 每个计数三次，因此去除四次多余的计数。 最终答案是12−4=8。 

对于 n=10 9，该算法执行与任何较小输入相同的恒定数量的操作。 每个顶点的数量是

 ⌊ 2 10 9 −1 ​ ⌋=499999999,

 所以初始计数是

 10 9 ⋅499999999=499999999000000000。 

因为 10 9 不能被 3 整除，所以不需要修正，该值就是最终的答案。
