 ## 解决方案
 ## 问题理解

 每个输入行描述一个日期，但其组成部分的顺序取决于分隔符。 点表示欧式顺序`day.month.year`，而斜杠表示美式顺序`month/day/year`。 任务不是确定该日期是否是真实的日历日期。 甚至诸如此类的东西`31.02.2001`仍然必须转换和打印。 

对于每个日期，我们都必须生成两种表示形式。 第一个总是有日、月、年的顺序，并使用点。 第二个总是有月、日、年并使用斜杠。 日和月必须恰好占据两位数，而年份必须恰好占据四位数字。 可以在解析期间删除输入中的前导零，然后在输出中恢复到所需的宽度。 

最多有 20,000 个输入日期。 每个日期仅包含三个小数字字段，因此没有理由使用比每行几个字符串或整数更复杂的数据结构。 处理每个日期一次的算法很容易足够快。 在这种规模下，即使每次约会的额外工作量恒定也可以忽略不计。 512 MB 内存限制也远远超出了所需，因为可以独立处理日期而无需存储整个输入。 

第一个微妙的情况是一位数年份。 例如，```
1
1.2.1
```必须成为```
01.02.0001 02/01/0001
```直接使用输入字符串的粗心实现可能会打印`01.02.1`，因为输入允许短年份，而输出始终需要四位数字。 

第二个边缘情况是已经填充的日期：```
1
01.02.0001
```输出依然是```
01.02.0001 02/01/0001
```转换不得意外地将前导零视为数值的一部分或产生不一致的宽度。 

第三种情况是无效的日历日期：```
1
29.02.2001
```所需的输出是```
29.02.2001 02/29/2001
```2001 年不是闰年，但有效性与任务无关。 添加日历验证将解决从未被问到的问题。 

第四种情况运用最大普通值：```
1
31/12/9999
```结果是```
31.12.9999 12/31/9999
```这里分隔符必须正确确定原始排序，并且年份必须保留四位数，无需任何特殊处理。 

## 方法

 故意的强力解释会将三个解析的组件视为无序集合，并尝试每种可能的排序，直到其中一个与所需的格式匹配。 只有`3! = 6`排列，因此对于 20,000 个日期中的每一个，最多将执行 120,000 次排列尝试，再加上格式化工作。 对于这些约束来说，它仍然足够快，但它解决了比必要的问题更困难的问题，并使代码更加复杂。 更重要的是，分隔符已经直接告诉我们顺序，因此无需搜索。 

蛮力方法之所以有效，是因为三个字段只有六种可能的排列，但作为工程选择却失败了，因为所有六种可能性都是不必要的。 输入分隔符唯一标识格式的观察结果将问题简化为一次确定性拆分和一次交换。 

对于点分隔日期，字段已按日、月、年顺序排列。 对于斜杠分隔的日期，前两个字段是月和日，因此只需交换它们。 一旦这三个字段按照日、月、年的顺序排列，格式就会很机械：将日和月填充为两个字符，将年份填充为四个字符。 

无需验证月份长度、闰年，甚至结果组合是否为真实日期。 输入保证每个分量都在其规定的数值范围内，而输出只是这些分量的标准化表示。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(6n) = O(n) | O(1) | O(1) | 已接受，但不必要的工作 |
 | 最佳 | O(n) | O(1) 辅助空间 | 已接受 |

 ## 算法演练

 1. 读取一个日期字符串并检查其分隔符。 点表示字段按日、月、年排序，而斜杠表示字段按月、日、年排序。 分隔符为我们提供了没有任何歧义的格式。 
2. 将字符串拆分为三个部分。 我们将组件保留为字符串，因为唯一需要的转换是填充，并且字符串避免了不必要的整数转换。 
3、如果分隔符是点，则直接将三个字段赋值给`day`,`month`， 和`year`。 如果分隔符是斜杠，则将第一个字段分配给`month`，第二个到`day`，第三个到`year`。 
4. 垫`day`和`month`正好两个字符并且`year`正好四个字符。 填充而不是手动检查位数可以统一处理已填充和未填充的输入。 
5. 将欧洲代表构建为`DD.MM.YYYY`。 
6. 将美国表示构建为`MM/DD/YYYY`。 
7. 打印两个表示，中间用一个空格分隔。 每个输入行都是独立的，因此可以立即对下一个日期重复相同的过程。 

### 为什么它有效

 步骤 3 之后，三个变量始终按规范顺序表示相同的逻辑日期`day`,`month`,`year`，无论输入是如何写入的。 分隔符决定哪个分配是正确的，因此不可能有其他解释。 填充仅更改每个组件的文本宽度，而不更改其值。 因此，第一个构造的字符串始终将规范组件按照日-月-年的顺序放置，并具有所需的宽度，而第二个构造的字符串则按照月-日-年的顺序放置相同的组件。 由于不需要日历验证，因此每个允许的输入都会得到正确处理。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    for _ in range(n):
        s = input().strip()

        if '.' in s:
            day, month, year = s.split('.')
        else:
            month, day, year = s.split('/')

        day = day.zfill(2)
        month = month.zfill(2)
        year = year.zfill(4)

        european = f"{day}.{month}.{year}"
        american = f"{month}/{day}/{year}"

        print(european, american)

if __name__ == "__main__":
    solve()
```分隔符检查实现算法中的第一个决策。 由于输入恰好具有两个允许的分隔符之一，因此检查`'.'`就足够了。 替代情况必须以斜线分隔。 

两个分支中的分配顺序是解决方案的关键部分。 为了`11.12.2000`，分裂产生`["11", "12", "2000"]`，这已经意味着日、月、年。 为了`1/29/3000`，分裂产生`["1", "29", "3000"]`，表示月、日、年，因此前两个变量故意以相反的顺序分配。`zfill`无需算术即可处理每个允许的宽度。`zfill(2)`树叶`"11"`不变和转换`"1"`到`"01"`。 相似地，`zfill(4)`皈依者`"1"`到`"0001"`和`"2100"`遗迹`"2100"`。 这也避免了一个简单的错误，即仅填充日期和月份，而年份保留其输入宽度。 

整数不可能溢出，因为该实现永远不会对日期组件执行算术运算。 它也不检查日期是否有效，这是正确的，因为无效日期仍必须格式化。

 ## 边缘情况

 ### 一位数年份

 对于输入```
1
1.2.1
```分隔符是一个点，所以组件是`day = "1"`,`month = "2"`， 和`year = "1"`。 衬垫生产`01`,`02`， 和`0001`。 因此两个输出是`01.02.0001`和`02/01/0001`。 该算法从不假设输入年份已经有四个字符。 

### 已经填充的值

 对于```
1
01.02.0001
```分割产生的字段已经具有所需的宽度。 呼唤`zfill`不添加任何东西，因为`zfill`使字符串等于或高于请求的宽度不变。 输出是```
01.02.0001 02/01/0001
```这使得规范化对于正确格式化的输入具有幂等性。 

### 日历日期无效

 对于```
1
29.02.2001
```该算法不检查二月的天数。 它只是简单地解析`29`,`02`， 和`2001`，填充它们，并构造两个表示。 结果是```
29.02.2001 02/29/2001
```这正是问题所需要的，即使该日期不是有效的公历日期。 

### 斜杠分隔输入

 对于```
1
1/29/3000
```分隔符是`/`，所以解析器分配`month = "1"`,`day = "29"`， 和`year = "3000"`。 填充后的值为`01`,`29`， 和`3000`。 欧洲形式变成`29.01.3000`，而美国形式则变为`01/29/3000`。 这种情况捕获了最可能的解析错误，该错误将斜杠分隔的输入视为已经按日-月-年顺序排列。
