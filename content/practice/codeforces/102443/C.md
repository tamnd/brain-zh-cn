 ## 解决方案
 ## 问题理解

 该程序考虑每个四元组`(a, b, c, n)`正整数与`n >= 3`。 它的排序有两个级别。 首先，四元组按其四个坐标中的最大值进行分组。 在这样一个组中，它们按字典顺序排序`(a, b, c, n)`。 对于每个四元组，我们只需要打印是否`a^n + b^n`大于或小于`c^n`。 

输入给出两个位置`l`和`r`在这个无限的序列中。 我们必须准确地重建占据这些位置的四元组并打印它们相应的不等式。 

困难在于`l`和`r`可以大到`10^12`。 即使请求的间隔最多包含`10^4 + 1`答案是，位置本身可以远离序列。 生成所有先前的四元组是完全不可行的。 

约束中隐藏着一个有用的界限。 如果每个坐标最多`m`，那么有`m^3(m-2)`可能是四倍，因为`a`,`b`， 和`c`每个都有`m`选择同时`n`有`m-2`选择来自`3`通过`m`。 自从`1001^3 * 999`已经大于`10^12`，每个请求的位置最多属于一个具有最大值的组`1001`。 尽管序列本身很大，但这使得最大值的搜索空间非常小。 

有几个订购细节很容易处理错误。 

第一个四元组是`(1,1,1,3)`，所以指数开始于`3`，不在`1`。 例如，输入`1 1`必须产生`1^3+1^3>1^3`。 一个处理的实现`n`范围从`1`将立即构建错误的序列。 

两个最大值之间的转变是另一个常见的差一陷阱。 最后一个具有最大值的四元组`3`是`(3,3,3,3)`，有位置`27`。 下一个四元组是`(1,1,1,4)`，在位置`28`。 因此输入`28 28`产生`1^4+1^4>1^4`。 搜索包含以下位置的组`<=`错误的一方可能会改变整个小组后来的每个答案。 

事实上，最大值可能已经出现在词典前缀中的较早位置，这一事实也改变了有效完成的数量。 例如，有一次`a=M`，以后的每个坐标都可以自由选择，直到`M`，因为四元组已经有最大值`M`。 另一方面，当`a<M`，其余坐标必须包含`M`。 忽略这种区别会给前缀提供错误的四元数，从而选择错误的元组。 

最后，比较本身必须使用实际的整数幂。 例如，`(3,3,2,3)`给出`3^3+3^3 > 2^3`。 Python 整数具有任意精度，因此我们可以直接计算这些幂而不会溢出。 

## 方法

 直接的解决方案将完全按照所需的顺序枚举四元组。 对于每个可能的最大值`M`，我们可以枚举所有值`a`,`b`,`c`， 和`n`，跳过没有最大值的组合`M`，直到到达位置`r`。 这是正确的，因为它确实遵循序列的定义。 

问题在于迭代次数。 第一个`M`组一起包含`M^3(M-2)`四倍，所以到达周围的位置`10^12`需要处理关于`10^12`四倍。 即使不考虑计算能力的成本，一万亿次迭代也远远超出了时间限制。 通过平方求幂来计算每个幂会增加另一个对数因子。 

关键的观察是我们永远不需要生成前面的四元组。 我们可以计算给定最大值之前存在多少个四元组，通过二分搜索找到包含所请求位置的最大值，然后使用前缀计数找到该最大组内的每个坐标。 

对于固定的最大值`M`，所有坐标都位于`[1,M]`和`n`在于`[3,M]`。 最多有最大值的四元组总数`M`是`F(M) = M^3(M-2)`。 

因此，最大值恰好为的四元组`M`占据职位`F(M-1)+1`通过`F(M)`。 

定位后`M`，我们知道该组内所请求的位置。 然后我们重建`(a,b,c,n)`从左到右。 在每个坐标处只有两个相关案例。 如果前缀已经包含`M`，所有剩余坐标均不受限制。 如果没有，则选择一个小于`M`意味着后面的某个坐标必须等于`M`。 

对于固定位置，每个候选值小于`M`具有相同数量的有效完成。 价值`M`具有不同的完成次数，因为它立即满足最大要求。 这种每个候选者常量的结构使我们能够通过二分搜索找到正确的坐标，而不是扫描所有值。 

暴力破解之所以有效，是因为它完全遵循序列，但当请求的等级变大时就会失败。 每个前缀都可以代数计数的观察结果让我们可以直接跳到所需的组，然后跳到所需的四元组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(r log M)`算术作业|`O(1)`| 太慢了|
 | 最佳 |`O((r-l+1) log M)`|`O(r-l+1)`用于输出| 已接受 |

 这里`M <= 1001`，所以对数因子很小。 输出本身最多可以包含`10001`线，因此存储答案也很便宜。 

## 算法演练

 1. 定义`F(M) = M^3(M-2)`。 

这计算了每个四元组，其四个坐标最多为`M`， 和`n`仅限于`3..M`。 因此`F(M)`正是属于最大值的最后一个位置`M`。 
2.二分查找最小的`M`满意的`F(M) >= rank`。 

这标识了包含所请求位置的最大组。 该组的第一个位置是`F(M-1)+1`，所以设`k = rank - F(M-1)`。 

现在`k`是组内以一为基础的位置，其最大值恰好为`M`。 
3. 重建`a`,`b`,`c`， 和`n`从左到右。 

维护一个布尔值`maxed`表示已选择的前缀是否包含`M`。 最初它是假的。 

为了`a`， 如果`a<M`，然后其中之一`b`,`c`， 或者`n`必须等于`M`。 完成数为`M^2(M-2) - (M-1)^2(M-3)`。 

如果`a=M`，最大条件已经满足并且有`M^2(M-2)`完成情况。 

这些计数对于每个`a<M`，所以我们可以二分查找最小的`a`累计完成数达到`k`。 
4.选择后`a`，减去属于较小值的元组的数量`a`，然后更新`maxed`如果`a=M`。 

同样的想法适用于`b`。 如果最大值尚未出现，则每个`b<M`有`M(M-2) - (M-1)(M-3)`完成情况，同时`b=M`有`M(M-2)`完成情况。 

如果最大值已经出现，则每个`b`正好有`M(M-2)`完成情况。 
5. 将同样的推理应用到`c`。 

如果`M`还没有出现，选择`c<M`力量`n=M`，所以正好有一个完成。 选择`c=M`允许每个指数`n`从`3`通过`M`, 给予`M-2`完成情况。 

如果最大值已经出现，则每个`c`有`M-2`可能的指数。 
6. 手柄`n`最后的。 

如果最大值已经出现，则有效指数恰好是`3,4,...,M`，按此顺序。 本地排名直接决定`n = 3 + k - 1`。 

如果选择后还没有出现最大值`c`， 然后`n`被迫成为`M`。 
7. 使用Python 的任意精度整数比较两侧。 

打印`a^n+b^n>c^n`当左侧较大时，否则打印`a^n+b^n<c^n`。 

费马大定理保证这些正整数不会出现相等的情况`n>=3`。 

### 为什么它有效

 中心不变量是`k`始终是已固定前缀的所有有效补全中所需元组的字典顺序。 对于每个候选坐标，我们精确计算有多少个以该候选坐标开头的有效元组。 由于字典顺序将所有具有较小候选者的元组放在前面，因此累积完成计数达到的第一个候选者`k`必须是所需元组的坐标。 删除所有先前的候选者后，相同的不变量适用于下一个坐标。 

完成计数是正确的，因为只有两种可能性。 如果最大`M`已经出现了，每个剩余的坐标都可以独立地取任何允许的值。 如果没有出现，选择下面的值`M`要求剩余坐标包含`M`，通过减去限制为的分配来计算`1..M-1`。 这给出了每个前缀表示的元组的确切数量，因此每个二分搜索都会选择正确的词典坐标。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def total(m):
    if m < 3:
        return 0
    return m * m * m * (m - 2)

def find_maximum(rank):
    lo, hi = 3, 4

    while total(hi) < rank:
        hi *= 2

    while lo < hi:
        mid = (lo + hi) // 2
        if total(mid) >= rank:
            hi = mid
        else:
            lo = mid + 1

    return lo

def choose_coordinate(m, k, pos, maxed):
    if pos == 0:
        if maxed:
            small = big = m * m * (m - 2)
        else:
            small = (
                m * m * (m - 2)
                - (m - 1) * (m - 1) * (m - 3)
            )
            big = m * m * (m - 2)

    elif pos == 1:
        if maxed:
            small = big = m * (m - 2)
        else:
            small = (
                m * (m - 2)
                - (m - 1) * (m - 3)
            )
            big = m * (m - 2)

    else:
        if maxed:
            small = big = m - 2
        else:
            small = 1
            big = m - 2

    lo, hi = 1, m

    while lo < hi:
        mid = (lo + hi) // 2

        if mid < m:
            count = mid * small
        else:
            count = (m - 1) * small + big

        if count >= k:
            hi = mid
        else:
            lo = mid + 1

    value = lo

    before = (value - 1) * small
    k -= before

    return value, k

def get_tuple(rank):
    m = find_maximum(rank)

    k = rank - total(m - 1)

    a, k = choose_coordinate(m, k, 0, False)
    maxed = (a == m)

    b, k = choose_coordinate(m, k, 1, maxed)
    maxed = maxed or (b == m)

    c, k = choose_coordinate(m, k, 2, maxed)
    maxed = maxed or (c == m)

    if maxed:
        n = 3 + k - 1
    else:
        n = m

    return a, b, c, n

def solve(data):
    l, r = map(int, data.split())

    ans = []

    for rank in range(l, r + 1):
        a, b, c, n = get_tuple(rank)

        left = a ** n + b ** n
        right = c ** n

        if left > right:
            op = '>'
        else:
            op = '<'

        ans.append(f"{a}^{n}+{b}^{n}{op}{c}^{n}")

    return '\n'.join(ans)

def main():
    data = input()
    sys.stdout.write(solve(data))

if __name__ == "__main__":
    main()
```这`total`函数实现累计计数`F(M)`。 特殊情况`m<3`需要，因为当最大值低于时没有合法指数`3`。`find_maximum`首先通过加倍找到安全上限，然后执行标准下限二分搜索。 这避免了依赖于派生界限`M<=1001`在实现中，而边界解释了为什么搜索仍然非常小。`choose_coordinate`包含核心计数参数。 这`pos`参数标识我们是否选择`a`,`b`， 或者`c`。 变量`small`是任何候选者的完成次数小于`M`， 尽管`big`是当候选人本身是时的完成数`M`。 

什么时候`maxed`是真的，`small`和`big`是相等的，因为已经满足了最大要求。 当它是假的时候，`small`通过减去从不使用的配置来获得`M`。 这个减法是关键的组合步骤。 

二分查找要求第一个坐标，其元组的累积数量至少为`k`。 对于以下候选人`M`，累积计数很简单`candidate * small`。 为了`M`， 这是`(M-1)*small + big`。 找到坐标后，`(value-1)*small`元组已被跳过，因此该数量已从`k`。 

指数是单独处理的，因为它的合法范围从`3`，并且因为它是最后一个坐标。 一次`M`都已经出现了`M-2`指数值可用。 如果它没有出现，指数必须等于`M`。 

比较使用精确的整数算术。 涉及的最大功率大约为`1001^1001`，只有几千个十进制数字长，所以 Python 的任意精度整数就足够了。 没有浮点舍入，也没有溢出风险。 

## 工作示例

 对于第一个样本，前四个位置都属于最大值`3`团体。 自从`F(2)=0`和`F(3)=27`，局部排名等于全局排名。 

| 全球排名| 最大限度`M`| 当地排名`k`|`a`|`b`|`c`|`n`| 输出|
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 3 | 1 | 1 | 1 | 1 | 3 |`1^3+1^3>1^3`|
 | 2 | 3 | 2 | 1 | 1 | 2 | 3 |`1^3+1^3<2^3`|
 | 3 | 3 | 3 | 1 | 1 | 3 | 3 |`1^3+1^3<3^3`|
 | 4 | 3 | 4 | 1 | 2 | 1 | 3 |`1^3+2^3>1^3`|

 对于排名`1`，元组`(1,1,1,3)`被选中。 对于排名`2`，第一个坐标仍然存在`1`，第二个仍然是`1`，第三个前进到`2`。 相同的字典顺序过程产生剩余的两个元组。 

作为第二个跟踪，考虑可能请求的最大排名`10^12`。 我们有`F(1000) = 998,000,000,000`尽管`F(1001) = 1,001,999,997,999`。 

因此排名位于`M=1001`组，在本地位置`2,000,000,000`。 

坐标重建进行如下。 

| 舞台|`k`之前|`small`|`big`| 选择值|`k`之后|
 | --- | --- | --- | --- | --- | --- |
 |`a`| 2,000,000,000 | 2,998,999 | 2,998,999 1,000,998,999 | 1,000,998,999 667 | 667 2,666,666 | 2,666,666
 |`b`| 2,666,666 | 2,666,666 1,999 | 1,999 999,999 | 999,999 1001 | 1001 667,666 |
 |`c`| 667,666 | 1 | 999 | 668 | 668 334 | 334
 |`n`| 334 | 334 1 | 1 | 336 | 336 334 | 334

 选择后`b=1001`，最大值已经出现，因此后面的每个坐标都不受限制。 得到的四元组是`(667,1001,668,336)`。 自从`b`大于`c`，通过比较立即知道有`a^n+b^n > c^n`为积极的`n`，所以输出是`667^336+1001^336>668^336`。 

该轨迹表明，即使位置接近`10^12`仅通过少量的二分搜索而不是通过数十亿个先前的元组来重建。

 ## 边缘情况

 对于最小输入`1 1`，二分查找发现`M=3`因为`F(2)=0`和`F(3)=27`。 本地排名为`1`，所以第一个坐标是`1`，那么第二个是`1`，那么第三个是`1`，最后`n=3`。 结果正是`1^3+1^3>1^3`。 这捕获了意外允许指数的实现`1`或者`2`。 

对于输入`27 27`，局部排名为`27`, 最大的最终位置`3`团体。 因此每个坐标被选择为`3`，生产`(3,3,3,3)`。 输出是`3^3+3^3>3^3`。 这会检查特殊的`M`候选者收到其更大的完成计数，并且不会跳过组的最终元组。 

对于输入`28 28`,`F(3)=27`，因此搜索移动到`M=4`。 本地排名变为`1`。 按字典顺序排列的最小元组，其最大值恰好为`4`是`(1,1,1,4)`，因为最大值一定出现在某个地方并且`n`是最后一个坐标，使其成为第一个位置`4`可以出现，同时保持所有早期坐标等于`1`。 输出是`1^4+1^4>1^4`。 这是将全局排名转换为局部排名的关键边界情况。 

对于最大输入`10^12 10^12`，最大组为`M=1001`。 本地排名为`2,000,000,000`，重构给出`(667,1001,668,336)`。 外观`1001`在`b`立即将前缀标记为相对于最大条件完整，因此其余坐标被选择为普通字典值。 最终的对比是`667^336+1001^336>668^336`。 这证实了计数方法在序列中很远的地方仍然有效，而无需枚举前面的`10^12`元组。
