 ## 解决方案
 ## 问题理解

 我们有一个十进制整数寄存器。 开始于`a`，我们可以执行两种操作。 加法运算使寄存器增加`9x`对于任意正整数`x`。 删除操作会删除一些正数的前导十进制数字，但每个删除的数字都必须是`1`。 寄存器恰好是的特殊情况`1`包含在内，因为删除该单个数字会产生`0`。 

这项任务是建设性的。 给定`a`和`b`，我们必须打印最多一个序列`1000`改变寄存器的操作`a`到`b`，或打印`Broken`如果不存在这样的序列。 中间寄存器值最多只能保留`10^18`。 输入值本身最多是`10^9`，因此它们最多包含十个小数位。 

位数少是关键限制。 我们不需要最短的序列，并且我们有一个非常慷慨的限制`1000`与最多需要处理的十位数字相比的操作。 这强烈表明正确的解决方案应该逐位处理十进制表示形式，而不是搜索可能的寄存器值。 

粗心的解决方案也可能会失败，因为前导零从普通的十进制表示中消失。 例如，考虑`a = 100`。 处理完第一个数字后，剩下的概念后缀是`00`，但寄存器将其简单存储为`0`。 构造必须使用其位数来推断后缀的位置，而不是假设寄存器的当前十进制长度等于未处理的位数。 

另一个边缘情况是`a = 0`和`b = 0`。 不需要任何操作，所以正确的输出可以简单地`Stable`其次是`0`。 盲目尝试处理数字的结构`0`就好像它是一个正数可能会产生无效的操作。 

案例`a = 1`,`b = 9`也具有指导意义。 我们可以转型`1`进入`0`通过添加`9`并删除前导`1`，然后变换`0`进入`9`通过添加另一个`9`。 因此有效序列是`+ 1`,`- 1`,`+ 1`。 该示例使用较短的序列，`+ 2`,`- 1`，但最小化是无关紧要的。 

最后，解决方案必须尊重`10^18`中间界限。 如果加法产生的数字大于允许的限制，仅仅找到代数上正确的构造是不够的。 下面的数字结构在允许的输入范围内创建最多 18 位小数的数字，并且其最大可能的中间值保持在下面`10^18`。 

## 方法

 一个自然的暴力想法是将每个寄存器值视为一个状态并从`a`到`b`。 从一个状态我们可以尝试通过增加`x`，我们也可以尝试一切可能的有效删除。 原则上这是正确的，因为每个合法操作都将表示为状态图中的一条边。 

问题在于状态空间巨大。 即使我们将自己限制在以下值`10^18`, 最多有`10^18 + 1`可能的寄存器值。 对于这种特定的结构来说，逐一尝试添加的情况甚至更糟。 例如，当构建一个数字时`1`在足够高的小数位上，所需的乘数可以是`12,345,679`乘以 10 的幂。 对于完全由 1 组成的九位数字目标，所需的最大`x`是`1,234,567,900,000,000`，因此进行强力搜索来测试`x = 1, 2, 3, ...`可能需要超过`10^15`候选人在一个位置进行检查。 这`1`第二个限制立即排除此类搜索。 

有用的观察是乘以`9`与十进制数字和紧密相关。 如果我们想将一个前导数字变成一个前导数字序列，我们可以选择一个整数，将其乘以`9`正是创建了那些。 

假设当前号码以数字开头`d`，后跟精确的后缀`k`小数点位置。 为了`d >= 1`，考虑通过书写形成的数字`1, 2, ..., d`。 例如，对于`d = 4`这是`1234`。 身份`4 + 9 * 1234 = 11110`就是我们需要的模式。 一般来说，`d + 9 * 123...d = 11...110`恰好与`d`领先者。 如果整个表达式乘以`10^k`，删除前导后缀后，后缀保持不变。 这让我们可以删除第一个数字`a`。 从左到右处理所有数字最终会转换`a`化为零。 

朝相反方向走略有不同。 假设我们已经有了目标的后缀并且想要在前面添加数字`d`。 我们可以添加 9 的倍数，以便结果以几个 1 开头，后跟所需的数字和现有后缀。 选择前导数字的数量，以便新数字与现有后缀具有相同的模九余数。 由于十进制数的模九余数与其数字和相同，因此选择`9 - d`领先者`1 <= d < 9`使添加量可以被九整除。 为了`d = 9`，不需要领先的。 

这给出了直接构造`0`对任何`b`。 结合这两个结构给出`a -> 0 -> b`。 

每个数字最多需要两次运算，因此每个数最多十位，整个序列最多四十次运算，远低于`1000`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |

 ## 算法演练

 1. 阅读`a`和`b`作为字符串。 保留字符串很有用，因为构造取决于原始小数位置，包括否则将从寄存器表示中消失的零。 
2. 构建一个可转换的序列`a`进入`0`。 处理数字`a`从左到右。 让`k`是当前数字右侧的位置数。 
3. 如果当前数字是`0`，不发出任何操作。 当前寄存器已经在数字上准确地表示了剩余的后缀，因此无需删除任何内容。 
4. 如果当前数字是`d >= 1`，构造整数`123...d`。 例如，`d = 1`给出`1`,`d = 2`给出`12`， 和`d = 5`给出`12345`。 添加`9 * 123...d * 10^k`，由操作表示`+ (123...d * 10^k)`。 
5、本次相加后，当前的前导数字和相加的数量正好相加`d`前导，后跟未更改的后缀。 删除那些`d`领先者使用`- d`。 此操作后的不变性是已处理的第一位数字已消失并且寄存器等于未处理的后缀。 
6. 在所有数字之后`a`已处理完毕，寄存器为`0`。 这会自动处理前导零，因为零位不需要任何操作。 
7. 现在构建`b`从零开始。 处理数字`b`从右到左。 在每一点，寄存器都包含后缀`b`已经建成了。 
8. 如果新的数字是`9`， 添加`9 * 10^k`， 在哪里`k`是已经构造的后缀位数。 这直接改变了当前后缀的前缀`S`进入`9S`，所以不需要删除。 
9. 如果新的数字是`d`， 在哪里`1 <= d < 9`, 准确选择`9 - d`领先者。 构造整数`C`由数字组成`1, 2, ..., 8-d`， 其次是`10-d`。 例如，`d = 2`给出`C = 1234568`， 尽管`d = 8`给出`C = 2`。 
10.添加`C * 10^k`通过印刷`+ C * 10^k`。 结果寄存器包括`9-d`前导，然后是所需的数字`d`，那么后缀就已经构造好了。 删除第一个`9-d`数字使用`- (9-d)`。 寄存器现在是正确的较长后缀。 
11. 连接来自的操作`a -> 0`相和`0 -> b`阶段。 由于每个非零数字最多创建两个运算，并且每个数字最多有十位数字，因此最多有四十个运算。 

### 为什么它有效

 第一阶段的不变性是处理后的位置`j`，寄存器恰好包含从位置开始的十进制后缀`j+1`。 对于一个数字`d >= 1`, 身份`d + 9 * 123...d = 11...110`准确地创造`d`前导数字，因此删除这些数字会精确删除已处理的数字。 乘以`10^k`保留后缀位置。 因此，每个已处理的数字都会被删除，而不会更改任何未处理的数字。 

对于第二阶段，假设已经构建的后缀是`S`下一个目标数字是`d < 9`。 我们创建了一些表格`111...1 d S`和`9-d`领先者。 其位数之和超过`S`正是通过`9`，所以它等于`S`模九。 因此，它们的差可以被九整除，并且可以通过加法运算产生。 删除后`9-d`领先的，寄存器就变成了`dS`。 为了`d = 9`，直接添加`9 * 10^k`给出`9S`。 因此，每个目标数字都可以正确地添加到前面。 

这两个阶段是独立的，因为第一个阶段始终以零结束，第二个阶段以零开始。 由于每个操作在构造上都是合法的并且每个中间值都是有界的，因此最终寄存器恰好是`b`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_to_zero(s):
    ops = []
    n = len(s)

    for i, ch in enumerate(s):
        d = ord(ch) - ord('0')

        if d == 0:
            continue

        # 123...d
        c = 0
        for x in range(1, d + 1):
            c = c * 10 + x

        k = n - 1 - i
        x = c * (10 ** k)

        ops.append(("+", x))
        ops.append(("-", d))

    return ops

def build_from_zero(s):
    ops = []
    n = len(s)

    for i in range(n - 1, -1, -1):
        d = ord(s[i]) - ord('0')
        k = n - 1 - i

        if d == 0:
            # A zero cannot be introduced by deleting leading ones,
            # but it is already represented by the positional suffix.
            continue

        if d == 9:
            # Add 9 * 10^k, which simply prepends digit 9.
            ops.append(("+", 10 ** k))
            continue

        # We want:
        #
        #   111...1 d S
        #
        # with 9-d leading ones.
        #
        # The difference from S must be divisible by 9.
        c = 0
        for x in range(1, 9 - d):
            c = c * 10 + x
        c = c * 10 + (10 - d)

        x = c * (10 ** k)

        ops.append(("+", x))
        ops.append(("-", 9 - d))

    return ops

def solve():
    a, b = input().split()

    ops = build_to_zero(a)
    ops.extend(build_from_zero(b))

    print("Stable")
    print(len(ops))
    for typ, value in ops:
        print(typ, value)

if __name__ == "__main__":
    solve()
```这`build_to_zero`函数直接实现从左到右的不变量。 变量`k`是当前数字之后的小数位数，因此将构造的值乘以`10^k`使新创建的前导前缀出现在未触及的后缀之前。 

循环构造`c`故意使用数字`1`通过`d`。 由此产生的身份是第一阶段的核心。 例如，与`d = 3`,`c = 123`， 和`3 + 9 * 123 = 1110`。 

这`build_from_zero`函数反转方向。 它是`k`计算右侧已经构建了多少个目标位置。 对于来自的数字`1`通过`8`，值`c`选择这样的数字，以便乘以 9 后创建的数字恰好包含`9-d`领先者。 随后的删除操作将删除这些数字，并将所需的数字保留在现有后缀的前面。 

这`d == 9`案件是分开的，因为`9-d`为零。 没有什么可删除的，添加即可`9 * 10^k`只需插入一个`9`在正确的位置。 

零在构造中不需要显式操作。 它们在后面的步骤中通过位置乘法来处理。 这就是为什么即使寄存器本身存储整数，原始输入也必须保留为字符串。 

Python 整数不会溢出，但构造也考虑到问题的数值界限。 输入不大于`10^9`，唯一的十位输入是`1000000000`，其第一位数字是`1`; 因此，构造的中间值仍然低于`10^18`。 操作次数最多为四十次。

 ## 边缘情况

 对于`a = 0`和`b = 0`，两个构造函数都返回一个空的操作列表。 算法打印`Stable`和`0`，这正是最简单的有效变换。 无人工`+`或者`-`需要进行操作。 

对于包含零的数字，请考虑`a = 100`。 第一个数字是`1`，所以算法添加`10^2`对象，意味着寄存器增加`900`，改变`100`进入`1000`。 删除前导`1`树叶`0`。 剩余的两个零位不生成任何操作。 这是有效的，因为它们的位置已经通过处理第一个数字时使用的 10 的幂来计算。 

对于包含零的目标，请考虑`b = 900000009`。 该算法构建了最终的`9`第一的。 中间的零不需要显式操作，因为当后面的前导`9`插入后，其 10 的幂已使其距现有后缀 9 个位置。 因此，该结构将零点创建为位置间隙，而不是尝试单独制造它们。 

对于数字`9`，一般的删除构造需要零个前导，这不是有效的删除操作。 该算法通过添加来单独处理这种情况`10^k`物体，产生增加`9 * 10^k`。 这直接在数字前面加上`9`，所以不需要删除。 

对于数字`1`，出现相反的极端。 从零开始构建它时，我们需要八个前导。 例如，`0 + 9 * 12345679 = 111111111`; 删除八个前导叶子`1`。 数量`12345679`不是任意的。 其位数和为`37`，结果的乘积完全具有所需的十进制结构。 

对于最大输入`1000000000`，第一阶段仅进行初始建设`1`。 该操作使用`10^9`，生产`10^10`，删除前导的结果为零。 其余零不需要任何操作。 这个案例也解释了为什么`10^18`绑定是安全的：约束允许的唯一十位输入具有这种特殊形式，因此我们永远不会遇到以大的非零数字开头的十位数字。 

最后的微妙之处在于输出序列不必是最小的。 为了`1 -> 9`，该示例具有两次操作的构造，而简单的`a -> 0 -> b`施工用三。 因为后者更长而拒绝后者会误解输出要求。 唯一重要的限制是合法性`1000`操作界限，`10^18`中间界限，并达到准确的目标。
