 ## 解决方案
 ## 问题理解

 我们在二维平面上绘制了多达十万个三角形。 画布一开始完全是红色的。 每个三角形都按照非常特定的绘制规则依次应用：三角形的边界永久涂成黑色，而严格位于三角形内部的每个点的颜色都以红色→绿色→蓝色→红色的循环前进。 三角形外的点不变。 一旦一个点变成黑色，它就不会再改变。 

处理完所有三角形后，我们必须确定最终图片是否仅包含黑色和红色点。 如果这是真的，我们输出“nice”。 否则，我们必须产生任何最终变成绿色或蓝色的点。 

这些约束立即排除了任何逐点模拟。 该域是连续的，每个三角形都会影响整个区域，因此最终状态是平面上的分段恒定着色。 对于多达 100,000 个三角形，任何重新计算每个查询点每个三角形覆盖范围的方法都远远超出了 2 秒允许的范围，因为即使$O(n^2)$运营将围绕$10^{10}$。 

关键的困难在于答案与顶点或网格点等离散对象无关。 三角形可以在其内部创建绿色或蓝色区域，并且该区域可以通过与其他三角形的重叠来分割。 因此，失败案例不是孤立的点，而是整个开放区域。 

一些边缘案例有助于阐明天真的推理可能会出现什么问题。 

一个错误是假设仅检查三角形顶点就足够了。 例如，两个重叠的三角形可以严格在两个三角形内部创建蓝色区域，而所有顶点保持红色或黑色。 另一个错误是假设只有整数格点才重要。 着色是在所有实点上定义的，因此即使所有输入都是整数，绿色区域也可能出现在无理坐标处。 

第三个微妙的问题是黑色边界永远不会再改变，但它们无助于简化内部逻辑。 他们只是从考虑中删除边界点； 它们不能防止内部重叠引起的颜色循环。 

## 方法

 直接的暴力视图是选择一个候选点并计算有多少个三角形内部包含它。 如果模 3 的计数不为零，则该点为绿色或蓝色。 在许多候选点上重复这一点最终会找到证人（如果存在的话）。 然而，困难的部分是保证我们不会错过所有相关区域。 平面被所有三角形边划分为面，并且每个面具有恒定的覆盖计数。 在最坏的情况下，此类面的数量可能是二次的，因此显式地构造它们是不可能的。 

真正的观察是，我们永远不需要所有面，只需要一个具有非零覆盖率模 3 的面。我们可以将问题视为维护由三角形边缘引起的平面细分，并跟踪当我们穿过边缘时覆盖率如何变化，而不是构造完整的排列。 每个三角形对凸区域的内部贡献+1，并且穿过排列的任何边缘都会将覆盖计数改变固定量。 这将问题转化为找到累加值模 3 为非零的任何区域。 

解释这个问题的一个实用方法是，平面被三角形边划分为单元。 在每个单元格内，“覆盖三角形的数量 mod 3”值是恒定的。 所以我们只需要检测是否所有单元格的计算结果都为零。 如果不是，我们可以通过取该区域的任何内点来从任何非零单元中恢复代表点。 

避免显式构建排列的标准方法是使用扫描线透视：我们按照所有三角形顶点和边缘事件的 x 坐标的顺序处理平面的垂直切片。 在两个连续的 x 事件之间，与垂直线的活动交点是简单的线段，每个三角形在该切片上贡献一个连续的 y 间隔。 我们在 y 上维护一个段结构，用于存储模 3 的覆盖计数，并检查是否有任何间隔变为非零。 当找到这样的线段时，我们重建其中的一个点并将其输出。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 朴素点检查 |$O(n^2)$每个查询|$O(1)$| 太慢了 |
 | 扫线排列 |$O(n \log n)$到$O(n \log n)$坐标压缩平均|$O(n)$| 已接受 |

 ## 算法演练

 1. 收集三角形顶点的所有 x 坐标并对它们进行排序以定义垂直扫描事件。 这些是活动交叉口结构可以改变的唯一位置。 
2. 对于每个三角形，计算其内部与给定 x 处的垂直线的 y 交点。 由于三角形是凸三角形，因此该交点始终是单个线段，可以通过沿每条边的 x 的两个线性函数来描述。 
3. 在连续 x 事件之间的扫描期间，维护由投影覆盖当前 x 板的三角形贡献的所有活动 y 段。 每个三角形恰好贡献该板中的一个 y 间隔。 
4. 在压缩的 y 坐标上维护线段树。 每个节点存储模 3 的覆盖范围。当当前板中的三角形处于活动状态时，我们在其 y 间隔上加 +1，当它离开时，我们减去 1。这确保结构始终反映当前的 x 位置。 
5. 对slab 应用更新后，检查树中是否存在任何具有非零值的段。 如果存在这样的段，则沿树向下提取具体的 y 坐标，并将其与当前板内的任何 x 配对以生成有效的见证点。 
6. 如果没有板产生非零段，则该函数在任何地方都相同地以 3 为模 0，因此图片仅包含黑色和红色点，我们输出“nice”。 

为什么它有效可以归结为平面细分的稳定性。 该平面被三角形边划分为单元，并且在每个单元内，覆盖三角形内部的数量是恒定的。 扫描线永远不会错过任何单元，因为每个单元在某些 x 板中都显示为连续间隔，并且覆盖范围的每次变化都会在穿过边缘端点时准确触发。 因此，如果任何区域具有模 3 的非零覆盖率，则它必须出现在至少一个扫描间隔中，并且线段树将检测到它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, ys):
        self.ys = ys
        self.n = len(ys) - 1
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.tree = [0] * (2 * self.size)
        self.lazy = [0] * (2 * self.size)

    def _apply(self, idx, val):
        self.tree[idx] = (self.tree[idx] + val) % 3
        self.lazy[idx] = (self.lazy[idx] + val) % 3

    def _push(self, idx):
        if self.lazy[idx]:
            v = self.lazy[idx]
            self._apply(idx * 2, v)
            self._apply(idx * 2 + 1, v)
            self.lazy[idx] = 0

    def update(self, l, r, val, idx=1, nl=0, nr=None):
        if nr is None:
            nr = self.size
        if r <= nl or nr <= l:
            return
        if l <= nl and nr <= r:
            self._apply(idx, val)
            return
        self._push(idx)
        mid = (nl + nr) // 2
        self.update(l, r, val, idx * 2, nl, mid)
        self.update(l, r, val, idx * 2 + 1, mid, nr)

    def query(self, idx=1, nl=0, nr=None):
        if nr is None:
            nr = self.size
        if self.tree[idx] == 0:
            return None
        if nr - nl == 1:
            return nl
        self._push(idx)
        mid = (nl + nr) // 2
        res = self.query(idx * 2, nl, mid)
        if res is not None:
            return res
        return self.query(idx * 2 + 1, mid, nr)

```该实现的核心结构是压缩 y 坐标上的线段树，它维护垂直切片的模 3 覆盖计数。 这段缩短的代码中缺少的部分是每个扫描板的 y 间隔更新的精确构造，这取决于计算三角形与垂直线的交点。 在完整的实现中，每个三角形为每个板贡献一个连续间隔，该间隔是从沿其边缘的线性插值得出的。 

线段树是让我们无需显式枚举排列即可检测任何非零区域的关键机制。 

## 工作示例

 考虑一个简单的配置，其中两个重叠的三角形覆盖中心区域两次。 在该区域中，覆盖范围为 2，因此红色变为蓝色。 当扫描线进入重叠部分时，线段树将显示一个非零值。 

| 步骤| 活跃三角形| 板坯覆盖率| 发现非零 |
 | ---| ---| ---| ---|
 | 1 | 第一个三角形 | 1 | 是的 |

 这会立即在第一个三角形内产生一个见证点。 

现在考虑三个完全重叠的相同三角形。 里面的每个点都被恰好覆盖 3 次，所以红色又变回红色。 线段树从不报告非零区间，因此输出是“nice”。 

| 步骤| 活跃三角形| 板坯覆盖率| 发现非零 |
 | ---| ---| ---| ---|
 | 1 | 所有三个三角形 | 3 模 3 = 0 | 没有|

 这证实了对消模 3 的处理是正确的。

 ## 边缘情况

 一个微妙的情况是三角形仅在边界上重叠。 由于边界点始终是黑色且永不改变，因此它们不会影响内部覆盖计数。 扫描线仅跟踪严格的内部间隔，因此仅边界相交不会产生误报区域。 

另一种边缘情况是完全取消，其中三角形以每个点都被恰好覆盖 3k 次的方式重叠。 在这种情况下，每个线段树节点在整个扫描过程中都保持为零，并且不会产生见证。 

第三种情况是不相交三角形。 每个三角形独立创建一个覆盖范围为 1 的区域，因此与任何三角形内部相交的第一个处理的板会立即产生绿色或蓝色点。
