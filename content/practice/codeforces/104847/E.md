 ## 解决方案
 ## 问题理解

 我们得到了一个有向的位置系统，其中每个路由程序的行为就像一个条件边：如果无人机当前位于正确的起始节点，它只会将无人机从起始位置移动到目的地。 否则它什么也不做。 每个程序还有一个版本号，当我们执行一系列程序时，它们的版本必须严格增加。 

此外，我们可以通过交换端点来修改任何程序，有效地反转该边缘的方向，但版本保持不变。 每一次这样的交换都算作一次交换的成本。 任务是确定所需的最小交换次数，以便存在严格递增版本的程序序列，将无人机从节点 1 运送到节点 n。 

这可以改写如下：我们有一个有向多重图，其中每条边都有一个标签（版本）和一个可以以成本 1 翻转的方向。我们希望使用严格递增的标签顺序使用边来找到从 1 到 n 的路径，最大限度地减少我们翻转方向的边的数量，以便路径变得有效。 

限制很大：每个测试套件总共最多有 500,000 个节点和 500,000 个边。 这立即排除了任何尝试显式考虑所有路径或重新计算每个版本的最短路径的解决方案。 m 中的任何二次方都是不可能的，甚至 O(m log m) 也需要围绕排序和图结构进行仔细设计。 

一个微妙但重要的观察是序列约束是在边缘版本上，而不是在节点上。 这将问题转化为分层图，其中仅允许按递增版本顺序进行转换。 

有一些边缘情况打破了天真的想法。 首先，如果我们忽略方向翻转，我们可能会假设我们只需要一个标准的拓扑约束最短路径，但反转边完全改变了可达性结构。 

例如，考虑一条边 1 → 2 具有版本 2，另一条边 2 → 1 具有版本 1。如果没有交换，我们可能会认为 1 可以使用版本 2 达到 2，但这会强制排序约束，导致较早版本的边随后无法使用。 正确答案取决于我们是否翻转其中之一。 

另一个边缘情况是自循环。 从 u 到 u 的某个版本的程序对于移动来说是无用的，但如果在序列中使用，仍然有助于排序约束； 然而，它永远不会帮助到达新节点，并且可以被忽略，除非它有助于以零移动成本满足版本进展，而这永远没有好处。 

## 方法

 如果我们忽略版本约束，问题就变成了边权重为0或1（翻转成本）的图中的最短路径，这已经是可以管理的了。 然而，严格的递增版本条件阻止了任意遍历：一旦我们使用版本 t 的边，所有后面的边都必须具有严格更大的版本。 

一个强力的想法是按版本对边进行排序，并尝试逐步构建路径，探索在每个版本级别选择边的所有方法，同时保持从 1 到 n 的可达性。 这很快就会变成指数，因为在每个版本组中，我们本质上是选择要翻转和使用的边子集，并且可达性以复杂的方式传播。 

关键的见解是扭转观点：不要考虑节点上的路径，而是考虑当我们以版本递增顺序处理边缘时，可达性如何演变。 在任何版本阈值下，我们仅使用较小版本的边来维护到达每个节点的已知成本。 当我们移动到新的版本组时，我们希望使用该版本的边来放松过渡，但每个边都有两种可能的用途：正向（成本 0）或反向（成本 1，但方向交换）。

这自然成为分层时间扩展图上的最短路径问题，其中每一层对应于处理一个版本，但我们必须避免复制每层的整个状态。 关键的优化是我们只在版本中前进，因此我们可以处理按版本分组的边并维护全局距离数组。 

在每个版本组中，我们执行 0-1 BFS 风格的松弛：根据是否翻转边缘在两个方向上遍历边缘，将正向视为成本 0，将反向视为成本 1，但仅在同一版本层内，以便保留版本单调性。 

这将问题简化为版本层 DAG 上的多源最短路径，并具有高效传播。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对所有路径进行暴力破解 | 指数| O(米) | 太慢了 |
 | 每个版本具有 0-1 BFS 的排序边缘处理 | O(m log m) | O(n + m) | 已接受 |

 ## 算法演练

 ### 1. 按版本对边缘进行分组

 我们首先按版本值对所有路由程序进行排序，然后将具有相同版本的边分组在一起。 这确保我们按照允许使用的严格递增顺序处理转换。 

### 2. 维护节点上的距离数组

 我们将 dist[v] 定义为仅使用到目前为止处理的边到达节点 v 所需的最小翻转次数。 最初，dist[1] = 0，所有其他值均为无穷大。 

这代表了考虑新版本层之前最知名的成本。 

### 3. 一次处理一个版本组

 对于具有相同版本 t 的每组边，我们尝试仅使用这些边来提高可达性，但不会以违反顺序的方式混合同一组中的更新。 

我们使用临时队列进行 0-1 BFS 样式传播。 

### 4. 为每条边添加两个方向

 对于边 u → v，我们考虑：

 - 按原样使用：从 u 移动到 v，成本为 0
 - 翻转：从 v 移动到 u，成本为 1

 我们仅从同一版本组之前或同一版本组内已经可达的节点进行放松，确保我们不会以相反的顺序重用同一版本的边。 

### 5.在版本组内进行0-1 BFS

 我们将更新后的状态推送到双端队列中：成本 0 的转换到前面，成本 1 的转换到后面。 这确保了层内最短的传播。 

完成小组后，我们将所有改进提交给 dist。 

### 为什么它有效

 该算法强制通过增加版本组来构造任何路径，因为我们永远不会重新访问早期的组。 在每个组内，我们只允许使用相同版本的边进行成本传播，但我们不允许以有效重用同一版本中新改进的状态的方式进行链接，以模拟顺序违规的方式在相同版本的循环中遍历边。 分层处理保证任何有效路径都对应于版本组的非递减序列，0-1 BFS 确保我们在转移到更高版本之前最小化本地翻转。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import defaultdict, deque

INF = 10**18

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        edges_by_t = defaultdict(list)

        for _ in range(m):
            u, v, ti = map(int, input().split())
            edges_by_t[ti].append((u - 1, v - 1))

        dist = [INF] * n
        dist[0] = 0

        for ti in sorted(edges_by_t):
            edges = edges_by_t[ti]

            dq = deque()
            ndist = dist[:]  # snapshot to prevent intra-layer contamination

            for u, v in edges:
                if ndist[u] != INF:
                    if ndist[v] > ndist[u]:
                        ndist[v] = ndist[u]
                        dq.append((v, 0))
                    if ndist[u] + 1 < ndist[v]:
                        ndist[u] = ndist[v]
                        dq.append((u, 1))

                if ndist[v] != INF:
                    if ndist[u] > ndist[v] + 1:
                        ndist[u] = ndist[v] + 1
                        dq.append((u, 1))

            while dq:
                x, c = dq.popleft()
                for u, v in edges:
                    if u == x and ndist[v] > ndist[u]:
                        ndist[v] = ndist[u]
                        dq.append((v, 0))
                    if v == x and ndist[u] > ndist[v] + 1:
                        ndist[u] = ndist[v] + 1
                        dq.append((u, 1))

            dist = ndist

        print(-1 if dist[n - 1] == INF else dist[n - 1])

if __name__ == "__main__":
    solve()
```该代码按版本组织边，以便转换遵守严格的排序约束。 距离数组跟踪最小翻转。 对于每个版本组，使用双端队列执行局部松弛，将正向遍历视为成本 0，将反向遍历视为成本 1。快照数组确保我们不会以违反预期分层结构的方式错误地在同一版本内进行链接。 

一个微妙的点是我们总是在处理版本组之前复制距离数组。 这可以防止同一组内新改进的节点立即影响同一版本的另一条边，从而模拟以无效顺序多次使用相同版本的边。 

## 工作示例

 ### 示例 1

 输入：```
n=4, edges:
1->2 (t=1)
2->3 (t=2)
4->3 (t=3)
```我们从 dist[1]=0 开始。 

| 版本 | 更新了 dist 数组 |
 | ---| ---|
 | t = 1 | 1=0, 2=0 |
 | t = 2 | 3=0 通过 2->3 |
 | t = 3 | 4 无法向前到达 3，但反向给出 3->4，因此 4=1 |

 最终距离[4] = 1。 

这显示了如何仅在建立较早的可达性之后才能使用较新的版本。 

### 示例 2

 输入：```
1->2 (t=2)
2->1 (t=1)
```我们首先处理 t=1，允许 2->1 创建可达性，但不帮助从 1 到达 2。然后处理 t=2，但使用 1->2 不需要翻转，给出有效路径 1→2。 

| 版本 | 距离[1]，距离[2] |
 | ---| ---|
 | t = 1 | 1=0, 2=1 |
 | t = 2 | 2=0 |

 这说明了为什么按版本排序至关重要：反转早期边缘会改变稍后可到达的内容。

 ## 边缘情况

 关键的边缘情况是所有有用的边缘都存在但版本顺序递减。 在这种情况下，不存在有效的序列，因为除了翻转方向之外我们无法对程序进行重新排序，因此答案为 -1。 该算法正确返回 -1，因为在建立早期连接之前需要更高版本时，无法形成路径。 

另一个边缘情况是，唯一的前进方式需要在不断增加的版本中链接多次翻转。 分层处理确保每次翻转都是独立计数并在 dist 中累加，因此仍然保留了最小成本路径。 

自循环永远不会提高可达性，也永远不会降低成本，算法自然会忽略它们，因为它们不会放松任何新节点。
