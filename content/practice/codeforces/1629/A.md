[CF 1629A - 下载更多 RAM](https://codeforces.com/problemset/problem/1629/A)

 **评分：** 800
 **标签：** 暴力、贪婪、排序
 **求解时间：** 1m 21s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们被要求建模一个系统，在该系统中我们可以暂时使用 RAM 来永久增加 RAM。 每个软件都有两个数字：运行所需的 RAM 量，以及使用后提供的 RAM 量。 我们的 PC 启动时有一定的初始 RAM。 目标是确定按某种顺序运行软件可实现的最大 RAM，并遵守程序仅在当前 RAM 至少达到其要求时才能运行的规则。 我们获得了多个测试用例，每个测试用例都指定了软件项目的数量、起始 RAM 以及两个需求和收益列表。 每个测试用例的输出都是一个数字：我们可以达到的最大 RAM。 

限制很小：最多 100 个测试用例，每个测试用例最多有 100 个软件项目，RAM 值最多为 1000。这意味着即使每个测试用例使用 O(n²) 算法也是可行的，因为在最坏的情况下，我们将执行大约 100×100² = 10⁶ 操作，这在 1 秒的时间限制内是可以接受的。 我们不需要在时间上优化到 O(n log n)，但我们仍然需要一个清晰、正确的方法来处理所有边缘情况。 

当所有软件项目需要比我们最初拥有的更多的 RAM 时，就会出现不明显的边缘情况。 例如，如果初始 RAM 为 1，并且所有软件至少需要 2，则我们无法使用任何软件。 正确的输出是初始 RAM 本身。 当存在多个小需求程序时，会出现另一个微妙的情况：我们可能需要按特定顺序选择它们，以便稍后解锁更大增益的软件。 以任意顺序运行软件的粗心方法可能会错过这一点并低估最大 RAM。 

## 方法

 一种强力方法是尝试软件的所有排列。 对于每个排列，我们依次使用软件进行模拟并记录最终的 RAM。 这保证了正确性，因为它探索了所有可能的序列。 然而，排列的数量是n！，即使n=10，这也是不可行的。 因此，这种方法显然太慢了。 

关键的观察是，在每个时刻，最佳选择是运行 RAM 要求不超过当前 RAM 的任何软件。 在所有这些选择中，就可行性而言，顺序并不重要：任何现在可以使用的软件，如果我们推迟它，以后也可以使用。 因此，我们可以应用一个简单的贪心策略：重复选择任何要求最多为当前 RAM 的软件，应用它，并将其从列表中删除。 我们继续，直到没有更多的软件可用。 这是有效的，因为每个软件都会永久增加 RAM，从而为以前无法​​访问的软件提供运行的可能性。 可立即运行的软件之间的顺序不会影响可行性，但如果我们想以更少的步骤获得最大收益，则可能会影响效率； 这里，问题只要求最大RAM，所以任何顺序都足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 最优贪心 | O(n²) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 
2. 对于每个测试用例，读取 n 和初始 RAM k，然后读取 RAM 要求和增益的数组。 
3. 将每个软件的需求与其增益配对，创建元组列表（需求、增益）。 这简化了处理并确保我们可以跟踪剩余的软件。 
4. 当至少存在一个软件的要求≤当前RAM时，按顺序扫描列表以找到第一个这样的软件。 按软件增益增加当前 RAM 并将其从列表中删除。 重复此过程。 
5. 一旦没有软件可用，则打印当前 RAM 作为可达到的最大值。

为什么它有效：保持不变的是，在每次迭代时，都会考虑现在可以运行的所有软件。 通过运行任何此类软件，我们可以增加 RAM，从而使更多软件变得可用。 由于每个软件只能使用一次，所以我们最终会达到剩余软件都无法使用的状态。 此时，当前 RAM 已达到最大，因为在不违反要求的情况下无法执行其他软件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    software = list(zip(a, b))
    
    while True:
        progressed = False
        for i in range(len(software)):
            if software[i][0] <= k:
                k += software[i][1]
                software.pop(i)
                progressed = True
                break
        if not progressed:
            break
    print(k)
```在这个实现中，我们反复搜索当前可以运行的软件。 这`progressed`flag 跟踪我们在完整扫描中是否取得了进展。 使用`pop(i)`在找到可用的软件后立即确保我们不会重新考虑相同的软件。 我们在每次软件执行后都会中断，因为 RAM 发生了变化，可能会使以前无法使用的软件变得可用。 这可以避免在不更新 RAM 的情况下尝试一次性运行多个软件而出现的错误。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n²) | 对于每个测试用例，在最坏的情况下，我们扫描所有剩余的软件 n 次，每次扫描最多可以检查 n 个项目。 |
 | 空间| O(n) | 我们存储 n 个软件对的列表，并且没有额外的更大尺寸的数据结构。 |

 给定 n ≤ 100 且 t ≤ 100，该解决方案最多执行 10⁶ 迭代，在时间限制内轻松拟合。 内存使用量也远低于 256 MB 限制。
