 ## 解决方案
 ## 问题理解

 该问题提出了一种玩具编程语言，只有一个变量 _x_，最初设置为零。 程序的每一行都是一条递增或递减该变量的语句。 该操作可以出现在变量之前或之后，因此语句可以是`++X`,`X++`,`--X`， 或者`X--`。 我们的任务是在按顺序执行所有语句后确定 _x_ 的最终值。 

输入以语句数开始`n`， 其次是`n`行，每行都是有效的陈述。 输出是表示 _x_ 最终值的单个整数。 

鉴于限制条件，`n`最多 150 个，这对于现代计算机来说非常小。 这意味着即使是单独检查每个语句的简单方法也会立即运行。 无需担心大输入大小、整数溢出或性能优化。 

符号顺序会产生不明显的边缘情况。 由于该操作可以出现在之前或之后`X`，一个天真的检查`statement == "++X"`或者`statement == "X++"`可能会错过像这样的减量操作`X--`。 我们必须通过检查是否存在来检测增量和减量`++`或者`--`声明中的任何位置，而不仅仅是按位置。 例如，输入：```
3
++X
X--
--X
```最终值应为`0`，因为第一个递增，第二个递减，第三个再次递减。 

## 方法

 蛮力方法很简单。 初始化一个计数器`x`为零。 对于每个语句，检查字符串。 如果它包含`++`, 增量`x`; 如果它包含`--`, 递减`x`。 这是可行的，因为每条语句都包含一个操作和一个变量。 由于每个语句都是单独检查的，并且我们只对每个语句执行恒定时间的字符串搜索，因此总操作计数与`n`。 为了`n = 150`，这是微不足道的。 

这里没有有意义的“更快”算法，因为暴力方法已经以相对于语句数量的线性时间运行。 关键的见解是我们不需要按位置解析语句或将其标记化； 存在两个字符的运算符`++`或者`--`就足够了。 这一观察结果简化了实现并消除了与字符顺序相关的边缘情况。

 | 蛮力 | O(n) | O(1) | O(1) | 已接受 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化变量`x`为零。 这代表程序中唯一变量的当前值。 
2.读取语句的数量，`n`。 
3.对于程序中的每条语句，检查是否包含子字符串`++`。 如果是，则增加`x`。 
4. 如果语句包含`--`, 递减`x`。 
5. 处理完所有语句后，打印出的值`x`。 

为什么它有效：该算法保持了以下不变式：`x`始终反映迄今为止处理的所有语句的净效果。 每个语句都会修改`x`恰好为 1，无论是向上还是向下，并且每个语句都保证只包含一个操作。 因此，通过顺序扫描并更新`x`根据检测到的操作，保证最终值是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
x = 0

for _ in range(n):
    statement = input().strip()
    if "++" in statement:
        x += 1
    elif "--" in statement:
        x -= 1

print(x)
```解决方案首先读取语句数并初始化`x`。 对于每个语句，它会删除所有尾随换行符或空格，并检查是否存在递增或递减运算符。 我们使用`in`而不是位置检查，因为操作符可能出现在之前或之后`X`。 这确保了所有排列的正确性，例如`++X`或者`X++`。 最后，打印结果。

 ## 边缘情况

 主要的边缘情况是语句中符号的顺序。 例如，`X++`应该被完全一样地对待`++X`。 我们的算法处理这个问题是因为它检查子字符串`++`或者`--`声明中的任何地方。 

输入：```
2
X++
--X
```执行轨迹：

 | 步骤| 声明| x 之前 | x 之后 |
 | --- | --- | --- | --- |
 | 1 | X++ | 0 | 1 |
 | 2 | --X | 1 | 0 |

 输出是`0`，确认算法正确解释操作员位置。 这确保了不会由于操作符相对于变量的位置而产生相差一的错误。
