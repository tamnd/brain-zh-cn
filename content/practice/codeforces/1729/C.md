 ## 解决方案
 ## 问题理解

 我们得到一串小写字母，代表一行瓷砖。 每个位置都是从第一个字符到最后一个字符的路径中的一个节点，但我们不需要仅移动到相邻位置。 相反，我们可以从任何索引跳转到任何其他索引，并且跳转的成本仅取决于字母：它是它们的字母位置之间的绝对差异。 

任务是构建一条从索引 1 开始到索引 n 结束的有效路径，每个索引最多访问一次。 在实现总成本最小的所有路径中，我们必须选择使用最大索引数量的路径，这意味着我们希望在不增加最优成本的情况下插入尽可能多的中间站点。 

所以问题有两层：首先最小化总成本，然后在所有最小成本解决方案中最大化路径中的顶点数量。 

跨测试用例的总字符串长度最多为 2e5 的约束立即表明每个测试用例的解决方案为 O(n) 或 O(n log n)。 如果一个测试用例很大，单个字符串中的任何二次方都会失败。 

当多个字母按字母顺序位于端点之间时，会出现微妙的边缘情况。 例如，在像“az”这样的字符串中，任何像“m”这样的中间字母的成本取决于它与两个端点的距离，并且插入额外的节点可以根据结构保留或增加成本。 所有索引上的朴素最短路径将允许不必要地重新访问中间结构，但我们被禁止重新访问索引，因此不允许循环。 

关键的困难在于我们不仅仅是在具有任意边的图中找到最短路径。 我们必须利用边权重中的结构来避免考虑 O(n^2) 转换。 

## 方法

 一种直接的方法是将问题建模为具有 n 个节点的完整有向图上的最短路径，其中每对索引都有一个加权边。 运行 Dijkstra 将给出正确的最小成本，但当 n 达到 2e5 时，O(n^2 log n) 行为是不可能的。 

即使我们巧妙地限制转换，天真的观点仍然会考虑潜在的 O(n^2) 条边。 瓶颈在于每个节点都可以连接到每个其他节点，其成本仅取决于字母，而不是位置。 

关键的观察是，只有字母表中字符的相对顺序才重要，而不是它们的位置。 如果我们从字母的角度思考，任何最佳的移动都会更喜欢在附近的字母值之间移动，因为跨越大的字母间隙是昂贵的，并且不能分解为更便宜的中间步骤，除非这些中间步骤存在。 

这建议通过根据索引的特征对索引进行排序来压缩问题。 一旦索引按字母分组，我们只需要考虑按排序顺序相邻字母之间的转换。 在同一个字母内，所有位置的成本都是相等的，因此我们可以将它们自由链接以增加访问节点的数量而不影响成本。 

因此，最佳结构变成对字符值的单调遍历，访问按字母分组的所有索引，并进行排列，以便我们根据端点以频率边界的递增或递减顺序遍历字母。 

正确的构造简化为在字母表中选择 s[1] 和 s[n] 之间的方向，然后访问其字符按排序字符顺序位于它们之间的所有索引，对每个字符的出现进行分组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 完整图最短路径 | O(n^2 log n) | O(n^2 log n) | O(n^2) | O(n^2) | 太慢了|
 | 按字符排序/分组 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

1. 将每个字符转换为其字母表索引。 令开始为 s[1]，结束为 s[n]。 
2.如果开始和结束具有相同的字符值，则可以重新安排访问中间该字符的所有出现的任何路径，而不会增加成本。 最佳路径是访问具有该字符的所有索引，因为添加相同字母的移动不会增加成本。 
3. 否则，确定字母空间中的遍历方向。 如果起始值小于结束值，则向上移动； 否则我们会向下移动。 这个方向决定了我们包括哪些中间字符组。 
4. 收集按字符值分组的所有索引。 对于每个字符，存储它出现的所有位置。 
5. 按所选方向从起始值向结束值遍历字符。 对于严格位于它们之间的每个字符，以任意顺序附加其所有索引。 字符组内的顺序不会影响成本，因为所有字符组都具有相同的字母值。 
6. 将最终路径构造为：开始索引1，然后按遍历顺序收集所有中间索引，然后最终索引n。 
7. 通过对沿构造路径的连续字符值之间的绝对差求和来计算成本。 

这种排序有效的原因是，按字母表单调顺序移动可确保我们永远不会在较大的字母间隙上“回溯”，这会带来不必要的成本。 

### 为什么它有效

 成本函数仅取决于字母值，并且在整数 1 到 26 上类似于度量。任何最小化总成本的最佳路径都不能从遥远字母之间的振荡中受益，因为每次绕行都会增加绝对差异。 因此，最优解在端点之间的字母空间中必须是单调的。 一旦强制执行单调性，插入所有中间出现的字符就不会增加成本，因为在连续分组时，同一字符值内的重复访问贡献零增量字母表更改。 这保证了最小成本和最大访问索引数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)

        pos = [[] for _ in range(26)]
        for i, ch in enumerate(s):
            pos[ord(ch) - 97].append(i + 1)

        start = ord(s[0]) - 97
        end = ord(s[-1]) - 97

        path = [1]

        if start <= end:
            for c in range(start, end + 1):
                for idx in pos[c]:
                    if idx != 1 and idx != n:
                        path.append(idx)
        else:
            for c in range(start, end - 1, -1):
                for idx in pos[c]:
                    if idx != 1 and idx != n:
                        path.append(idx)

        path.append(n)

        cost = 0
        for i in range(len(path) - 1):
            cost += abs((ord(s[path[i] - 1]) - 97) - (ord(s[path[i + 1] - 1]) - 97))

        print(cost, len(path))
        print(*path)

if __name__ == "__main__":
    solve()
```该实现首先按字符对索引进行分组，这避免了位置之间的任何成对比较。 根据端点字符选择遍历方向，确保字母空间中的单调扫描。 

我们明确地将索引 1 和 n 从中间插入中排除以避免重复，因为端点始终是固定的。 

成本计算在施工后进行，以避免选择逻辑复杂化。 由于该路径在结构上已经是最优的，因此我们只验证其权重。

 ## 边缘情况

 当所有字符都相同时，就会出现一种边缘情况。 该算法将所有索引分组到一个字符下，并输出 1 到 n 之间的每个位置。 由于所有字母差异均为零，因此在最大化访问节点数量的同时成本保持为零。 该构造自然地按顺序包含所有指标，满足这两个目标。 

另一个边缘情况是严格递减的字符串，如“cba”。 该算法选择向下遍历并包含正确的反向字母序列中的所有索引。 尽管字符串中的位置没有排序，但分组可确保每次出现都只包含一次，并且成本保持最低，因为每一步仅在字母表空间中移动一个单位。 

第三种情况涉及混合字符，例如“abac”。 从a到c的遍历包括'a'和'b'组，确保没有跳过有益的中间字母。 该路径包括所有出现的“a”和“b”，从而最大化跳跃，而不会引入会增加成本的非单调过渡。
