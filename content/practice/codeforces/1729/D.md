 ## 解决方案
 ## 问题理解

 我们有一组朋友，其中每个朋友都有两个数字：他们打算在餐厅花多少钱以及他们实际有多少钱。 目标是将其中一些朋友分成不相交的组，每个组至少有两个人。 每个人最多只能使用一次，有些朋友可能会被完全排除在外。 

仅当该团体中的可用总资金至少等于该团体的计划总支出时，该团体才有效。 我们希望最大限度地增加我们可以形成的有效群体的数量。 

该结构不是单独分配预算，而是将人员配对，以便“盈余资金”共同弥补每个组内的“赤字”。 这立即表明这是一个平衡问题，而不是一个简单的匹配问题。 

这些限制促使我们寻求有效的解决方案。 由于所有测试用例中的朋友总数高达 100,000，因此每个测试用例的 n 为二次方的任何解决方案都太慢。 即使每个测试用例的 O(n log n) 是可以接受的，但任何比 O(n^2) 更糟糕的情况都是不可接受的。 

一个天真的想法是尝试所有可能的分区或通过检查子集贪婪地构建组。 这很快就会失败，因为子集的数量呈指数增长。 

一个更微妙的问题是分组决策相互作用。 一个拥有大量盈余的朋友可能在多个潜在群体中都有用，而糟糕的早期分组决策可能会减少最终的答案。 例如，如果我们贪婪地与一个强正和朋友和一个弱伙伴组成一个群体，我们可能会浪费原本可以平衡更大群体的强大盈余。 

关键的困难在于分组受到总和条件的限制，而不是个体可行性的限制。 

## 方法

 暴力解决方案会尝试将每个朋友分配到某个组并验证所有分区。 即使我们限制自己逐步建立群组，我们仍然需要在每一步中考虑剩余朋友的子集。 这会导致状态呈指数级增长，因为每个朋友都可以被放入任何组中或被排除在外。 即使进行了修剪，对于 n 高达 100,000 的最坏情况仍然难以解决。 

转折点来自于将每个朋友重新解释为贡献净值：他们的“预算减去成本”或$y_i - x_i$。 如果组中这些值的总和非负，则该组有效。 这将问题转化为形成总净值至少为零的组，并且每个组必须包含至少两个元素。 

一旦以这种方式看待，问题就类似于基于排序的净贡献对元素进行配对或分组。 如果我们按照有意义的顺序对朋友进行排序，我们就可以贪婪地决定哪些元素应该锚定群体，哪些元素应该支持他们。 

最优策略来自于按净值对朋友进行排序$d_i = y_i - x_i$。 积极的价值观是有益的，消极的价值观是有害的。 为了最大限度地增加群体数量，我们希望使用积极的贡献来“抵消”尽可能多的消极贡献。 A greedy two-pointer strategy naturally emerges: match the weakest (most negative) with the strongest (most positive), forming a group whenever their combined sum is non-negative, and continue inward.

 这在本质上类似于最优配对问题，其中极端值被匹配以最大化可行性。

 | 最优（排序+两个指针）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算每个朋友的净值：$d_i = y_i - x_i$。 这会将组的条件转换为单个数组上的总和约束。 如果所选组的总和是有效的$d_i$是非负的。 
2.全部排序$d_i$按非递减顺序。 这会将最大负值放在开头，将最大正值放在末尾，这样可以更轻松地推理配对极值。 
3. 初始化两个指针，一个在开始（左），一个在结束（右），并初始化一个组数计数器。 
4. 当左 < 右时，考虑将两个极值配对。 如果$d[left] + d[right] \ge 0$，那么这两个可以形成一个大小为 2 的有效组，因此我们计数一组并将两个指针向内移动。 这是最佳的，因为最强的可用值被用来补偿最弱的可用值，从而保留了剩余元素的结构。 
5. 如果$d[left] + d[right] < 0$，那么即使是最强的朋友也无法补偿最弱的朋友。 在这种情况下，我们通过向左移动来丢弃最弱的元素。 这是安全的，因为最弱的元素不能属于与任何其他剩余元素配对的任何有效组的一部分。 
6. 继续，直到指针重合。 成功配对的次数就是答案。 

### 为什么它有效

 正确性依赖于这样一个事实：在任何最佳解决方案中，我们都可以假设通过排序后配对极端相反的组来有效地形成组。 如果一个非常负的元素无法与可用的最大正元素配对，那么它也不能与任何其他元素配对，因为所有其他元素的帮助较小。 因此，丢弃它是安全的。 相反，每当最大的正数可以补偿最小的负数时，将它们配对总是安全的，因为用较小量级的伙伴替换任何一个都无法提高可行性。 这种贪婪的极值配对保留了强正值的最大使用，同时消除了最严格的负值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        x = list(map(int, input().split()))
        y = list(map(int, input().split()))
        
        d = [y[i] - x[i] for i in range(n)]
        d.sort()
        
        l, r = 0, n - 1
        ans = 0
        
        while l < r:
            if d[l] + d[r] >= 0:
                ans += 1
                l += 1
                r -= 1
            else:
                l += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```该实现首先将每个朋友折叠成一个净余额值。 这很重要，因为组约束仅取决于总数。 

排序确保我们总能推断出“最差”和“最好”的剩余候选者。 这两个指针模拟反复尝试使用最强的可用指针来营救最弱的参与者。 

条件`l < r`强制每个小组至少有两个人。 这直接匹配问题约束。 

当一对有效时，我们立即承诺。 如果不是，我们会丢弃最弱的元素，因为未来的配对无法比当前最强的候选元素更有效地拯救它。

 ## 边缘情况

 当所有净值均为负或零时，就会发生一种重要的边缘情况。 例如，如果每个朋友的消费都比他们拥有的多，则排序后的数组完全是非正数。 该算法反复丢弃最弱的值，因为与最强元素的有效配对无法达到非负和，从而导致零组，这与现实相符，因为没有两人组可以满足预算条件。 

另一种情况是只有一个强正值和许多轻微负值。 该算法确保最强的正值不会浪费在不可能的配对上。 仅当它实际上可以平衡较弱的元素时才使用它，否则较弱的负面元素将首先被丢弃。 

最后，当值紧密聚集在零附近时，每次配对尝试都会成功，并且算法会贪婪地形成下限（n/2）组，这是最佳的，因为每对都贡献一个有效的组，而没有剩余结构。
