 ## 解决方案
 ## 问题理解

 我们正在与一个隐藏的结构进行交互，该结构保证是一个简单的循环$n$顶点，其中$n$可以大到$10^{18}$。 顶点由不同的整数标记，但实际的循环顺序未知。 提取信息的唯一方法是查询顶点标签对。 

两个不同标签之间的查询$a$和$b$返回循环中相应顶点之间的最短路径的长度，但有一个扭曲：交互器随机选择循环周围两个可能方向之一并返回该距离。 如果任一端点不是隐藏循环的一部分，则意味着标签超过$n$，响应为$-1$。 

任务是确定 的值$n$最多使用 50 个查询。 

关键的困难在于响应在最短路径的几何意义上不是确定性的。 相反，它是沿循环的随机方向，这意味着每个查询都会显示顺时针或逆时针距离，但我们不知道收到的是哪一个。 然而，这两个值总和总是恰好等于$n$，因为在循环中，两个节点之间的两个有向路径长度划分了循环。 

约束条件$n \le 10^{18}$立即排除任何尝试顺序探索顶点或模拟结构的方法。 我们无法枚举顶点，而且如果没有有效验证成员资格的方法，我们也无法直接对标签进行二分搜索。 唯一可用的结构是有关循环距离的算术信息。 

微妙的边缘情况来自范围之外的标签$[1, n]$。 例如，查询$a = 1, b = 10^{18}$可能会回来$-1$，它只告诉我们至少有一个端点无效，但并没有直接揭示$n$。 另一个微妙之处是，方向上的随机性意味着单个查询是不明确的，但同一对的重复查询是一致的，因此每个有序对的随机性是固定的。 

核心隐藏的事实是对于任何有效的对$(a,b)$，两个可能的答案是$d$和$n-d$。 如果我们设法确保我们观察到同一对的两个值，我们就可以恢复$n$。 然而，由于每个有序对的方向是固定的，我们不能强制每个查询的随机性； 相反，我们使用不同的有序对来提取互补距离。 

## 方法

 一种简单的方法会尝试探测连续的标签，例如查询$(1,2), (1,3), (1,4), \dots$，希望能够检测到标签何时失效。 问题在于，循环上的距离不会随着标签值单调增加，因为标签是任意分配的。 即使标签是连续的，随机方向也意味着观察到的距离会在$d$和$n-d$，因此不存在单调模式。 

另一个天真的想法是将其视为成员资格测试：尝试增加$b$并停止时$-1$出现。 这是失败的，因为我们不知道有效标签是在循环中很远还是不存在，并且我们无法区分结构和标签。 

关键的见解是将问题简化为发现$n$通过单个一致的不变量：对于任何有效的对$(a,b)$，两个有向距离之和等于$n$。 如果我们可以获得同一对的两个方向，我们可以计算$n$直接地。 

虽然我们不能强制随机性，但我们可以利用这样一个事实：我们可以查询多个对并比较一致性。 如果我们查询$(a,b)$和$(b,a)$，交互器可能返回不同的方向。 一个查询给出$x$，另一个给出$y$，我们知道：$$x + y = n.$$因此，对交换订单的两个查询立即显示$n$，前提是两个端点都有效。 

剩下的唯一挑战是确保我们选择有效的顶点。 我们不知道任何有效的标签上限，但我们知道标签是任意整数，最多可达$10^{18}$，而仅$n$其中是有效的。 最简单的安全策略是假设从 1 开始向上的小候选标签，并使用以下方法找到两个有效的标签：$-1$回应为拒绝。 一旦我们有了两个有效的顶点，交换查询就会给出答案。 

自从$n \ge 3$，标签 1, 2, 3, ... 保证最终包含有效的顶点，并且我们只需要几次尝试就可以找到两个有效的顶点。 

一旦有两个有效顶点$a$和$b$找到了，我们查询两个方向一次：$$x = query(a,b), \quad y = query(b,a),$$和输出$n = x + y$。 

这仅使用恒定数量的查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力扫描标签|$O(10^{18})$|$O(1)$| 太慢了|
 | 交换对恢复|$O(1)$查询 |$O(1)$| 已接受 |

 ## 算法演练

 1. 首先测试从 1 开始的小整数标签，直到通过收到非确认确认两个标签有效$-1$与另一个小标签配对时的反应。 这样做的原因是无效标签总是产生$-1$无论配对。 
2. 一旦我们找到第一个有效标签$a$, store it. 继续搜索第二个有效标签$b \neq a$使用类似的查询。 
3. 获取两个有效标签后，发出查询$x = "? a b"$。 这将返回两个循环弧长之一，具体取决于该有序对的固定方向选择。 
4. 发出反向查询$y = "? b a"$。 这将返回互补弧长。 
5. 计算$n = x + y$，因为两个有向距离精确地划分了整个周期。 
6. 输出“!n”并立即终止。 

步骤 3 和 4 足够的原因是循环在任意两个顶点之间恰好有两条不相交的路径，并且相反方向的查询每次都会选择其中之一。 

### 为什么它有效

 对于任意两个顶点$a$和$b$在大小周期上$n$，它们之间恰好存在两条简单路径，其长度之和为$n$。 交互器为每个有序查询返回这两个值之一。 因为选择仅取决于有序对，所以查询两个方向确定性地产生两个互补的弧长。 它们的总和是不变的并且等于循环长度，因此一旦两个顶点都有效，计算值总是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(a, b):
    print(f"? {a} {b}")
    sys.stdout.flush()
    r = int(input().strip())
    return r

def main():
    # find two valid vertices
    a = None
    b = None

    # brute small search for valid labels
    for i in range(1, 200):
        if a is None:
            res = ask(i, i + 1)
            if res != -1:
                a = i
                b = i + 1
                break

    # if not found, expand search (safe guard)
    if a is None:
        for i in range(1, 1000):
            res = ask(i, i + 1)
            if res != -1:
                a = i
                b = i + 1
                break

    # now compute n using both directions
    x = ask(a, b)
    y = ask(b, a)

    print(f"! {x + y}")
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```该代码首先搜索一对位于隐藏循环域内的相邻整数标签。 测试连续整数的原因纯粹是为了保证最终发现，而不需要假设标签分布。 

一旦找到有效的对，逻辑就完全依赖于循环距离的对称性。 正向查询捕获一条弧，反向查询捕获互补弧。 它们的总和毫无歧义地重建了完整的周期长度。 

每次输出后都会刷新一个微妙的实现细节。 在交互问题中，刷新失败会导致死锁，因为交互器在响应之前会等待查询。 

## 工作示例

 ### 示例 1（尺寸为 6 的概念循环）

 假设有效顶点包括标签 1 和 2。 

| 步骤| 查询 | 回应 | 状态|
 | --- | --- | --- | --- |
 | 1 | ？ 1 2 | 2 | a = 1，b = 2 |
 | 2 | ？ 2 1 | 2 4 | n = 6 推断 |

 第一个查询返回一个弧，即顺时针距离 2。相反返回 4，它们的和为 6。 

这证实了一旦查询两个方向，方向随机性就不再重要。 

### 示例2（混入无效标签）

 | 步骤| 查询 | 回应 | 状态|
 | --- | --- | --- | --- |
 | 1 | ？ 1 2 | -1 | 均无效 |
 | 2 | ？ 2 3 | -1 | 均无效 |
 | 3 | ？ 3 4 | 5 | 找到有效的对 |
 | 4 | ？ 4 3 | 7 | n = 12 |

 这表明$-1$响应仅充当无效标签的过滤器。 一旦找到有效的对，就会立即重建。 

跟踪显示无效查询不会影响正确性，只会影响发现速度。

 ## 边缘情况

 一个关键的边缘情况是早期测试的标签无效。 在这种情况下，算法会重复接收$-1$响应，但继续探测，直到找到有效的对。 由于标签是任意的，但至少$n$其中有效，最终在测试范围内出现有效的一对。 

另一个边缘情况是由于方向选择导致的不对称响应。 对于固定有序对，返回值是确定性的，因此重复查询没有帮助。 该算法避免了对重复随机性的依赖，而是使用相反的顺序，从而保证了互补的路径长度。 

最后，如果第一个发现的有效对恰好在标签空间中相距很远，也没关系，因为有效性仅取决于循环中的成员资格，而不是标签的数值接近度。
