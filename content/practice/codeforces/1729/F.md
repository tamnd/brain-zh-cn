 ## 解决方案
 ## 问题理解

 我们得到一个数字字符串。 对于每个查询，我们查看原始字符串的一个子字符串，即`s[l..r]`，并计算其数值模`9`。 

单独地，我们可以选择任意两个不同的固定长度的子串`w`。 设他们的起始位置为`L1`和`L2`。 查询要求满足的位置$$v(L_1,L_1+w-1)\cdot v(l,r)+v(L_2,L_2+w-1)\equiv k \pmod 9$$在所有有效对中，我们必须最小化`L1`，其中，最小化`L2`。 

首先值得注意的是，实际数字可能非常大。 一个子串最多可以包含`2·10^5`数字，因此直接构造数字是不可能的。 幸运的是，条件只关心模余数`9`。 

所有测试用例的总长度最多为`2·10^5`，并且查询总数也最多为`2·10^5`。 任何检查所有长度对的算法`w`每个查询的子字符串都是无望的。 即使单个测试用例也可以包含大约`2·10^5`候选子串，所以二次工作将围绕`4·10^{10}`运营。 

该解决方案必须预处理所有长度 -`w`子字符串一次，然后在几乎恒定的时间内回答每个查询。 

一个微妙的一点是，答案不仅仅是任何有效的对。 词典最小化很重要。 考虑一种情况，其中残基类`3`包含起始位置`[2,7,20]`和残留类别`5`包含`[4,8]`。 如果两者都`(2,8)`和`(7,4)`满足模方程，正确答案是`(2,8)`因为`L1`较小。 粗心的实现如果在第一个有效的残基组合处停止，可能会返回错误的对。 

另一个容易犯的错误是忘记了`L1`和`L2`必须是不同的位置。 假设每个长度-`w`子串具有相同的残基，并且该残基仅出现一次。 然后禁止使用同一位置两次。 

例如：```
s = "111"
w = 2
```唯一长度为 2 的子字符串从以下位置开始`1`和`2`。 任何允许重复使用单个残基的逻辑都可能错误地产生`(1,1)`。 

前导零也是相关的。 子串`"000"`代表数字`0`，不是无效值。 因为我们只需要取模`9`，数字和自然地处理这个问题。 

## 方法

 蛮力的想法很简单。 对于每个查询，枚举每个可能的长度 -`w`子字符串作为首选和每个可能的长度 -`w`子字符串作为第二选择。 检查是否$$(a\cdot x+b)\bmod 9=k$$在哪里`a`是查询子串值模`9`， 和`x`,`b`是所选长度的残基-`w`子串。 

大致有`n-w+1`候选人。 在最坏的情况下，这大约是`2·10^5`，因此检查所有对的成本大致为$$(2\cdot10^5)^2 = 4\cdot10^{10}$$每个查询的操作。 那是完全不可行的。 

关键的观察是模`9`极大地压缩了搜索空间。 

对于任何十进制数，$$value \bmod 9 = (\text{sum of digits}) \bmod 9.$$每个长度-`w`子串属于仅有的九个残基类别之一，`0`通过`8`。 

我们只关心它的余数模，而不是记住每个子串值`9`。 对于每个残基`r`，我们存储所有长度的起始位置-`w`其值模数的子串`9`等于`r`。 

现在考虑一个查询。 让$$a = v(l,r)\bmod 9.$$我们需要残留物`x`和`y`这样$$(a\cdot x+y)\bmod 9 = k.$$只有`9×9=81`要检查的残基对。 

对于每个候选残基对，我们可以立即从存储的列表中确定字典顺序最小的有效位置。 由于 81 是常数，因此每个查询变为`O(81)`。 

剩下的任务是有效地计算子串残基。 使用数字前缀和，可以得到任意子串的数字和`O(1)`，因此它的模`9`值也可用于`O(1)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(m·n²) | O(n) | 太慢了|
 | 最佳| O(n + 81m) | O(n) | 已接受 |

 ## 算法演练

 1. 构建数字值的前缀和数组。 

让`pref[i]`是第一个的总和`i`数字。 那么任意子串的数字和为$$pref[r]-pref[l-1].$$2. 枚举每个长度-`w`子串。 

对于每个起始位置`i`，计算数字和`s[i..i+w-1]`使用前缀和并取模`9`。 
3. 按残基对起始位置进行分组。 

创建九个列表。 如果长度-`w`子串有残差`r`，将其起始位置附加到列表中`pos[r]`。 

因为我们从左到右扫描，所以每个列表内的位置会自动排序。 
4. 处理每个查询。 

计算$$a=v(l,r)\bmod 9.$$再次，数字和给出了这个`O(1)`。 
5. 枚举所有残基对`(x,y)`。 

检查是否$$(a\cdot x+y)\bmod 9 = k.$$只有这样的配对才能得出答案。 
6. 对于有效的残基对，确定最小的可用位置。 

如果`x != y`，最好的选择是第一个元素`pos[x]`和第一个元素`pos[y]`。 

如果`x == y`，我们需要两个不同的子字符串，因此残基类必须包含至少两个位置。 最佳选择是该列表中的前两个位置。 
7. 在所有候选答案中，保留字典顺序最小的一对。 

首先比较`L1`，然后由`L2`。 
8. 输出存储的对，或者`-1 -1`如果不存在候选人。 

### 为什么它有效

 每个长度-`w`子串仅由其余数模表示`9`。 查询条件仅取决于这些残基：$$(v_1\cdot a+v_2)\bmod 9 = ((v_1\bmod9)\cdot(a\bmod9)+(v_2\bmod9))\bmod9.$$因此用每个子串的残数替换它不会丢失任何信息。 

对于固定残基对`(x,y)`，字典顺序上最小的可用位置总是从相应列表中存储的最早出现的位置获得。 任何以后的发生只会增加`L1`或者`L2`。 

该算法检查每个可能的残基对。 由于每个子串都属于一个残基类别，因此每个有效答案都对应于所检查的对之一。 在所有可行的候选者中，选择字典顺序最小的、符合问题要求的候选者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        s = input().strip()
        n = len(s)

        w, m = map(int, input().split())

        pref = [0] * (n + 1)
        for i, ch in enumerate(s, 1):
            pref[i] = pref[i - 1] + int(ch)

        pos = [[] for _ in range(9)]

        for start in range(1, n - w + 2):
            end = start + w - 1
            rem = (pref[end] - pref[start - 1]) % 9
            pos[rem].append(start)

        for _ in range(m):
            l, r, k = map(int, input().split())

            a = (pref[r] - pref[l - 1]) % 9

            best = None

            for x in range(9):
                if not pos[x]:
                    continue

                for y in range(9):
                    if (a * x + y) % 9 != k:
                        continue

                    if x != y:
                        if not pos[y]:
                            continue
                        cand = (pos[x][0], pos[y][0])
                    else:
                        if len(pos[x]) < 2:
                            continue
                        cand = (pos[x][0], pos[x][1])

                    if best is None or cand < best:
                        best = cand

            if best is None:
                print(-1, -1)
            else:
                print(best[0], best[1])

solve()
```前缀和数组存储数字和而不是数值。 模数`9`，数字和和数字是等价的，这避免了处理巨大的整数。 

预处理阶段计算每个长度的余数`w`子串。 每个起始位置都插入到九个桶之一中。 因为位置是按升序处理的，所以桶的第一个元素自动是具有该剩余的最小起始位置。 

在查询处理过程中，残差`s[l..r]`是从相同的前缀和中获得的。 双循环结束`x`和`y`检查所有 81 种可能的残基组合。 每当一对满足模方程时，就会从相应的桶中提取最早的有效位置。 

特殊情况`x == y`需要照顾。 我们需要两个不同的子字符串，因此不能使用只有一个位置的桶。 前两个位置提供字典顺序上最小的有效对。 

Python 元组比较可以方便地实现所需的排序：`(a,b) < (c,d)`恰好意味着更小`L1`，如果相等，则更小`L2`。

 ## 边缘情况

 考虑：```
1
0000
1 1
1 4 0
```每个长度为 1 的子串都有残基`0`。 桶是：```
pos[0] = [1,2,3,4]
```查询子串也有残差`0`，所以方程变为：$$0\cdot x+y\equiv0\pmod9.$$选择`x=y=0`是有效的。 由于残基相等，该算法需要两个不同的位置并返回前两次出现的位置，`(1,2)`。 这可以正确处理前导零。 

现在考虑：```
1
12
1 1
1 1 5
```残渣桶有：```
pos[1] = [1]
pos[2] = [2]
```该算法检查所有 81 个残基对。 如果没有一个满足方程，`best`遗迹`None`和`-1 -1`被打印。 不会产生意外的答案。 

最后，考虑相同残基必须使用两次的情况：```
1
000
1 1
1 3 0
```这里：```
pos[0] = [1,2,3]
```残基对`(0,0)`满足方程。 该算法不使用`(1,1)`。 相反，它明确地占据前两个位置，产生`(1,2)`，它尊重所选子字符串不同的要求。
