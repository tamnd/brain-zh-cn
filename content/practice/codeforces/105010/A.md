 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，并允许对相邻的相等字符重复执行局部转换。 每当我们看到两个连续的`0`s，我们可以删除它们并插入一个`1`。 对称地，每当我们看到两个连续的`1`s，我们可以删除它们并插入一个`0`。 每个操作都会将字符串缩短一个字符，但也会更改我们压缩的块的值。 

这个过程可以重复任意多次，并且在每一步我们都可以自由选择任何有效的相邻对。 不同的选择可能会导致不同的中间字符串，但必须考虑所有有效的最终结果。 在通过这些转换可到达的所有字符串中，我们想要字典序上最大的字符串。 

这里的字典顺序与二进制字符串的平常行为一样，其中`1`大于`0`。 所以目标是推动尽可能多的`1`尽可能早地进入最终可到达的配置。 

约束允许每个测试用例最多 10^5 个字符，总体最多 2×10^5 个字符。 这立即排除了对所有子字符串的任何二次模拟或使用嵌套更新进行重复扫描。 即使是在每次操作后重新启动扫描的天真的贪婪算法，在最坏的情况下也会执行 O(n^2) 的工作，例如在长的相同字符块内交替减少。 

一个微妙的问题源于局部性。 该操作不会保留被删除的字符； 它翻转合并块的奇偶校验。 这意味着压缩段的效果取决于其邻居的结构，因此没有结构化表示的天真的“尽可能减少”策略很容易错过早期合并改变后来的可能性。 

作为具体的失败案例，请考虑`0000`。 如果我们贪婪地删除前两个零`1`，我们得到`1000`。 天真的继续可能会根据顺序给出不同的中间缩减，但真正的可到达空间包括多个折叠路径。 另一个例子是`111000`，其中一个区域内的合并会改变未来的合并是否会增加或减少词典价值。 如果没有一致的标准化策略，贪婪的选择可能会导致前缀不理想。 

关键的困难在于操作会破坏局部性：减少一对会改变邻接结构，并可能跨边界创建新的可约对。 

## 方法

 暴力方法将明确模拟所有可能的操作序列，在每个步骤中探索每个相邻的相等对。 由于每个操作的长度都会减少一，因此完整序列的深度为 O(n)，但分支通常会使状态数量呈指数增长。 即使修剪重复项也是不够的，因为不同的缩减顺序可能会产生不同的中间字符串，必须按字典顺序进行比较。 

关键的观察结果是，尽管有分支，系统仍然是汇合的：每当我们应用归约直到在归纳变换规则下不存在相邻的相等对时，最终结果并不取决于操作的顺序。 原因是该操作是本地的、对称的，并且总是用仅由该块确定的单个字符替换长度为 2 的块。 任何两个缩减序列最终都会协调一致，因为重叠缩减实际上对最终压缩结构有效。 

这允许我们直接使用堆栈来计算规范形式。 我们从左到右处理字符，保持当前减少的前缀。 每次追加一个字符时，我们都会检查最后两个字符是否相等。 如果是，我们用压缩结果替换它们，即翻转位。 这可能会再次创建与前一个元素的新相邻相等，因此我们继续传播约简。 

这种单遍标准化产生唯一的可达不可约字符串，并且由于所有可达字符串都简化为相同的形式，因此它也是字典上最大的字符串。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 堆栈标准化 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 维护一个表示当前转换后的字符串前缀的堆栈。 每个元素对应于迄今为止在所有缩减中幸存下来的字符。 这确保我们始终使用有效的中间状态。 
2. 从左到右迭代输入字符串，将每个字符推入堆栈。 我们将此视为扩展当前可达配置。 
3. 每次压入后，检查堆栈中的最后两个字符是否相等。 如果是，我们应用允许的操作：删除两者并用等于翻转位的单个字符替换它们。 这对转型进行建模`00 -> 1`和`11 -> 0`。 
4. 插入翻转位后，我们再次检查与前一个元素形成的新的相邻相等对。 如果存在这样的一对，我们重复相同的归约。 这种传播是必要的，因为单个合并可以级联为进一步的有效合并。 
5. 继续，直到堆栈末尾没有相邻的相等对为止，然后继续处理下一个输入字符。 
6. 处理完所有字符后，堆栈中包含规范缩减的字符串，这就是答案。 

### 为什么它有效

 不变的是，堆栈始终表示使用有效操作从处理后的前缀获得的可达配置，并且在堆栈边界处没有未处理的相邻相等对。 每次我们检测到相邻的相等对时，我们都会立即对其应用唯一有效的约简，因此不会出现未解决的可约模式。 由于约简严格地减少了长度，并且每个可能的约简序列最终都会导致完全约简的形式，因此堆栈过程收敛到一个唯一的固定点。 该固定点与归约顺序无关，因此它必须与字典顺序最大可达字符串一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def flip(c):
    return '1' if c == '0' else '0'

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    st = []
    for ch in s:
        st.append(ch)

        while len(st) >= 2 and st[-1] == st[-2]:
            x = st.pop()
            st.pop()
            st.append(flip(x))

    print("".join(st))
```该解决方案是围绕单个堆栈构建的，该堆栈演变成简化的规范形式。 帮手`flip`实现问题的变换规则。 内部循环是关键部分：每次插入后，它都会强制执行不变量，即不存在仍然可以压缩的两个相邻相等字符。 

重复的`while`循环至关重要，因为一次合并可能会暴露与前一个字符的另一个合并机会。 如果没有这种传播，堆栈将过早稳定并产生不​​正确的结果。 

## 工作示例

 考虑字符串`0000`。 

| 步骤| 堆栈| 行动|
 | --- | --- | --- |
 | 1 | 0 | 推|
 | 2 | - | 00 变成 1 |
 | 2 | 1 | 替换 |
 | 3 | 1, 0 | 推|
 | 4 | 1, 0, 0 | 推|
 | 5 | 1, 1 | 00 变成 1 |
 | 6 | 1 | 替换 |

 最终结果是`1`。 

该跟踪显示了级联减少：本地合并改变了未来的邻接结构，并且堆栈正确地传播了这些效果。 

现在考虑`0100`。 

| 步骤| 堆栈| 行动|
 | --- | --- | --- |
 | 1 | 0 | 推|
 | 2 | 0,1 | 推|
 | 3 | 0,1,0 | 推|
 | 4 | 0,1,0,0 | 推|
 | 5 | 0,1,1 | 00 -> 1 |
 | 6 | 0,0 | 11 -> 0 | 11 -> 0
 | 7 | 0 | 决赛|

 这个例子表明，减少可以在生产之间交替进行`0`和`1`，并且多个级联合并必须按顺序处理。

 ## 边缘情况

 完全统一的字符串，例如`0000...0`反复触发级联合并。 该算法可以正确处理此问题，因为每次合并都会减少堆栈并立即重新评估邻接关系，确保不保留任何隐藏的可简化结构。 

例如，`0000`收益为`00 -> 1`， 然后`11 -> 0`与堆栈中的其余结构交互后。 这个过程自然会持续到稳定为止。 

高度交替的字符串，例如`010101`不包含有效的相邻相等对，因此堆栈永远不会触发归约。 输出与输入保持相同，符合这样的配置不可能进行转换的事实。
