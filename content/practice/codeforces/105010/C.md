 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 每个测试用例都包含一段时间内的价格序列。 任务是查看价格严格逐步上涨的每个连续时间段，并测量从该段开始到结束的价格上涨了多少。 在所有这些增加的延伸中，我们希望最大可能的增加。 

更准确地说，我们考虑每个连续的子数组，其中每个下一个值都严格大于前一个值。 对于每个这样的子数组，我们取其最后一个值和第一个值之间的差。 测试用例的答案是所有有效子数组中最大的差异。 

限制因素有直接的影响。 跨测试用例的所有序列的总长度可以达到一百万。 这立即排除了任何尝试检查所有子数组甚至子数组内所有对的解决方案，因为这些方法会倾向于二次行为并超出时间限制。 我们需要对每个测试用例进行线性扫描。 

一些边缘情况很容易处理不当。 

一种情况是序列根本不增加。 例如，输入类似`5 4 3 2 1`不包含比一个元素长的严格递增连续子数组，因此答案为零。 

另一种情况是出现相同的值。 例如，`1 2 2 3`打破了相等对的递增条件。 该段`1 2`带来差异`1`， 和`2 3`带来差异`1`，所以答案是`1`， 不是`2`。 忽视严格性的粗心方法可能会错误地合并段。 

第三种情况是单元素数组。 只有一个值时，没有有效的增加，因此答案为零。 

## 方法

 暴力的想法是枚举每个可能的起始索引，然后在序列保持严格递增的情况下向前扩展，并计算起始和每个有效结束之间的差异。 这可以正确检查所有递增子数组。 然而，在完全递增数组的最坏情况下，每个起始点都会扩展到末尾，从而给出大约 N + (N-1) + ... + 1 次操作，每个测试用例的时间复杂度为 O(N²)。 当总 N 达到 10⁶ 时，这变得太慢了。 

关键的观察是任何最大严格增加的连续段的行为都是可预测的。 在这样的段内，每个元素都比前一个元素大，因此最小值是第一个元素，最大值是最后一个元素。 它内部的每个有效子数组产生的差异小于或等于从第一个到最后一个完整段的差异。 这意味着我们根本不需要考虑内部子细分。 

因此，任务简化为将数组拆分为最大严格递增游程。 对于每次运行，我们只需要其端点差异。 我们跟踪当前递增运行的开始，在条件成立时延长它，并在运行中断时更新答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N²) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(N) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例，并从左到右扫描数组，同时保持当前递增的段。 

1. 在索引 0 处开始一个新段。将其起始值存储为当前运行的候选最小值。 这代表当前严格递增块的第一个元素。 
2. 从左向右移动数组。 如果当前值严格大于前一个值，我们将保持在同一递增段内。 否则，该段在前一个位置结束。 
3. 当一个段结束时，将其贡献计算为最后一个值减去第一个值。 如果该值更大，请更新全局答案。 
4. 在当前位置开始一个新段，因为中断意味着增加的属性无法继续跨越此边界。 
5. 完成循环后，不要忘记处理最后一段，因为它不会以中断结束。 

### 为什么它有效

 在任何最大严格递增的连续段中，每个前缀最小值是第一个元素，每个后缀最大值是最后一个元素。 段内任何有效的递增子数组的第一个元素不小于段起点，最后一个元素不大于段终点，因此其差值不能超过全段差值。 因此，仅考虑段边界就足以捕获全局最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        if n == 1:
            print(0)
            continue
        
        ans = 0
        start = a[0]
        
        for i in range(1, n):
            if a[i] > a[i - 1]:
                continue
            else:
                ans = max(ans, a[i - 1] - start)
                start = a[i]
        
        ans = max(ans, a[-1] - start)
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案维护单个指针`start`它代表当前严格递增运行的第一个元素。 当运行中断时，我们通过将前一段的最后一个元素与`start`。 这避免了显式存储段边界。 

循环后的最终更新至关重要，因为最后一个段不会遇到中断条件，因此它的贡献将被错过。

 ## 边缘情况

 对于像这样的单元素数组`10`，算法初始化`start`作为唯一的值并立即输出零，因为没有可以形成递增段的转换。 最终贡献`a[-1] - start`变为零，匹配正确的结果。 

对于像这样的严格递减数组`5 4 3 2`，每一步都会触发一个分段。 每个段都有相同的起始值和结束值，因此每个段的贡献为零。 算法反复重置`start`正确并且永远不会合并非增加的部分。 

对于具有相等相邻值的数组，例如`1 2 2 3`，等式打破了两个 2 之间的段。 该算法最终确定了该段`1 2`给出 1，然后在 2 处开始一个新段，然后生成`2 3`给出 1。因此，最大值被正确计算为 1。
