 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 每个场景中都有$N$冠军，每个冠军都有一个初始力量值。 我们最多可以使用一次操作修改每个冠军一次：要么通过以下方式增加他们的力量：$K$，减少$K$，或保持不变。 将这些选择独立应用于所有冠军后，我们会查看所产生的优势并计算最大值和最小值之间的差异。 任务是以一种使最终差异尽可能小的方式选择操作。 

关键的限制是$N$每个测试用例最多 1000 个，总计$N$跨测试高达 5000。这已经表明$O(N^2)$或者$O(N \log N)$每个测试解决方案是可以接受的，但是如果重复 500 次，每次测试的任何立方体都会太慢。 的价值观$P_i$很大，高达$10^9$，因此我们不能依赖于小范围的频率数组或值压缩。 

天真的方法会尝试所有$3^N$加、减或不变的分配。 即使是为了$N=20$，这会爆炸，因此问题的结构必须允许更加受限的决策空间。 

出现微妙的边缘情况时$K = 0$。 在这种情况下，所有三个操作都是相同的，答案应该只是原始的最大值减去最小值。 另一个极端情况是当所有$P_i$是平等的； 那么最好的可能答案是 0（如果$K=0$) 或仍然为 0，因为我们可以一致地移动所有值而不改变分布。 

## 方法

 蛮力的想法是考虑每个元素的每个操作分配。 对于每个元素，我们选择$\{P_i - K, P_i, P_i + K\}$，然后计算结果范围。 这探讨了$3^N$每个测试用例的配置，甚至$N=30$这变得完全不可行。 由于每个元素独立地分支状态空间，因此成本呈指数增长。 

使这个问题变得更简单的结构是我们实际上并不关心单独的分配，只关心最终的最小值和最大值。 一旦数组被排序，极端的结果就主导了答案。 一个关键的观察是，最佳配置仅取决于我们将数组“拆分”为两组的位置：一些元素由$K$以及一些被推高的$K$，可能有一个可选的中间组。 

对数组进行排序后，考虑固定边界索引$i$。 左侧的所有元素都可以解释为要减少的候选元素$K$，而右侧的所有元素都是增加的候选元素$K$。 组内的任何混合分配都无济于事，因为它只会增加局部传播，而不会改善极端情况。 

这将问题减少到仅检查$N-1$分割点。 对于每个分割，我们计算减去后左侧部分中的最小可能值$K$，以及添加后右侧部分中可能的最大值$K$。 最好的答案是所有此类分割中的最小值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(3^N \cdot N)$|$O(N)$| 太慢了 |
 | 拆分+排序 |$O(N \log N)$|$O(1)$额外（除了输入）| 已接受 |

 ## 算法演练

 1. 按非降序对幂数组进行排序。 这确保了左侧和右侧的任何分区都对应于值空间中有意义的阈值。 
2. 将初始答案计算为最大可能值之间的差$P_{N-1} + K$和最小可能值$P_0 + K$或者$P_0 - K$，但我们将通过拆分来完善它。 这提供了一个基线。 
3. 对于每个索引$i$从$0$到$N-2$，将其视为两组之间的分割点。 索引处的元素$[0, i]$被认为减少了$K$，以及索引处的元素$[i+1, N-1]$被考虑增加$K$。 
4. 对于左组，运算后可能的最小值为$P_0 - K$，最大的是$P_i - K$。 对于右边的组，最小的是$P_{i+1} + K$，最大的是$P_{N-1} + K$。 对最终范围重要的唯一候选者是：

 的最小值$P_0 - K$和$P_{i+1} + K$，以及最大值$P_i - K$和$P_{N-1} + K$。 
5. 计算此分割的范围：$$\max(P_i - K, P_{N-1} + K) - \min(P_0 - K, P_{i+1} + K)$$6. 取所有分割中的最小值。 
7. 还与不使用拆分的情况进行比较，因为所有元素都可以根据哪个提供较小的扩展而统一增加或减少。 

为什么它有效

 排序后，任何最优分配都可以进行变换，使得所有“减少”选择形成前缀，所有“增加”选择形成后缀，而不增加范围。 如果存在较大元素减少而较小元素不减少的模式，则交换它们的操作不能增加最大值或减少最小值，并且通常会改善或保留范围。 这种交换论证迫使最优解进入单一阈值结构，使得对分割点的枚举就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        # baseline: all +K or all -K gives same range as original
        ans = a[-1] - a[0]

        for i in range(n - 1):
            high = max(a[i] - k, a[-1] + k)
            low = min(a[0] + k, a[i + 1] - k)
            ans = min(ans, high - low)

        print(ans)

if __name__ == "__main__":
    solve()
```解决方案从排序开始，这很重要，因为后面的推理取决于按全局顺序比较相邻值。 基线答案处理分裂没有好处的情况。 

在循环内部，每个索引充当“减少组”和“增加组”之间的假设边界。 的计算`high`和`low`应用两个变换后捕获最坏情况的极端情况。 然后减去得到结果范围。 

一个常见的实施错误是忘记包含基线案例，这在以下情况下很重要：$K = 0$或者当分割不能提高范围时。 另一个微妙的点是正确使用$a[i]$和$a[i+1]$作为边界代表； 混合这些指数会导致计算的区间出现相差一的错误。

 ## 边缘情况

 当$K = 0$，无论分配如何，每个元素都保持不变。 该算法仍然将基线计算为$a[-1] - a[0]$，并且每次分割都会产生相同的值，因为两者$+K$和$-K$是相同的。 所有配置中的最小值仍然正确。 

什么时候$N = 1$，排序产生单个元素。 分割点的循环不运行，答案直接$a[0] - a[0] = 0$，匹配单个值没有传播的事实。 

当所有值都相等时，唯一的变化来自于应用$+K$或者$-K$。 该算法正确地考虑了分割公式中的两个极端，最好的策略是将所有元素分配到相同的方向，产生零或对称分布，具体取决于$K$，但总是通过基线或崩溃极端的分裂正确地最小化。
