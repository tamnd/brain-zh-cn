 ## 解决方案
 ## 问题理解

 我们给定一个序列$P$它的行为应该像一些隐藏整数数组的前缀函数数组$A$。 位置处的前缀函数$i$告诉我们最长的长度$k$这样第一个$k$数组的元素与最后一个相同$k$以位置结束的元素$i$。 任务是重建任意数组$A$这将准确地生成这个前缀函数序列，或者决定不存在这样的数组。 

输出不是唯一的。 任何有效的构造都是可以接受的，只要我们计算它的前缀函数时，我们恢复给定的$P$。 

这些限制使得暴力破解变得不可行。 所有测试用例的总长度可达$2 \cdot 10^5$，因此每个测试用例的任何二次构造都会超时。 这强烈表明$O(n)$或者$O(n \log n)$每个案例的重建。 由于前缀函数结构本质上是向前方向上线性时间可计算的，因此逆构造也期望是线性的。 

一个微妙的边缘情况是前缀数组中的一致性违规。 例如，像这样的序列$P = [0, 2, 1]$立即不可能，因为$P_2 = 2$超出索引限制。 当隐含的边界结构与自身相矛盾时，就会发生另一种失败情况，例如$P = [0, 1, 2, 1]$，这会强制出现任何实际数组都无法实现的不兼容重叠。 贪婪地分配值而不跟踪边界一致性的幼稚方法将默默地生成其计算前缀函数偏离的数组$P$稍后在序列中。 

## 方法

 一个直接的想法就是尝试所有可能的数组$A$并计算它们的前缀函数，但即使对于小字母表，这也是指数函数$n$，因为每个位置可以采用多个值。 即使我们将值限制为一个小集合，我们仍然需要检查前缀重叠的一致性，这会花费$O(n)$每个候选人，使得整体搜索不可行。 

一种更结构化的方法是反转通常的前缀函数构造过程。 在前进的方向上，计算$P[i]$仅取决于先前构造的值。 这表明在重建时，我们可以维护一个候选数组$A$并逐步加强约束。 

关键的观察是每个位置$i$要么延伸先前的边界（当$P[i] > 0$）或打破它（当$P[i] = 0$）。 如果$P[i] > 0$，那么我们必须确保$A[i] = A[P[i]]$，因为长度的前缀$P[i]$必须匹配结尾为的后缀$i$。 如果$P[i] = 0$， 然后$A[i]$不得匹配$A[1]$，否则我们将创建一个长度为 1 的非零边界，这与前缀函数定义相矛盾。 

这提出了一种建设性的贪婪策略：将值分配给$A$同时强制执行由以下引起的平等约束$P[i]$。 每当需要新值时，我们都会引入新的符号。 我们还必须通过在构造过程中隐式重新计算前缀函数行为来验证隐含结构是否自洽。 

效率来自于将值视为等价类而不是任意整数。 每个位置要么复制较早的位置，要么引入新的符号，并且这种映射可以在线性时间内维持。

 ## 算法演练

 我们构建$A$增量，同时保持一致性$P$。 

1.初始化一个空数组$A$。 我们将从左到右分配值，使用整数作为符号。 
2. 对于每个位置$i$， 如果$P[i] > 0$，我们必须强制执行$A[i] = A[P[i]]$。 这直接编码了边界要求：以结尾的后缀$i$必须匹配长度前缀$P[i]$。 
3.如果$P[i] = 0$，我们分配一个新符号$A[i]$，但前提是这不违反任何先前隐含的等式约束。 如果$i > 1$，我们确保这个新符号不匹配$A[1]$，否则会出现长度为1的边框。 
4. 分配后$A[i]$，我们维护一个允许我们传播等式约束的结构。 如果一个位置$i$被分配为等于$A[j]$，那么所有未来的引用$i$必须尊重这种等价性。 
5. 构造完整数组后，我们在线性时间内计算其前缀函数并将其与$P$。 如果它们在任何位置不同，我们输出-1； 否则，构造的数组有效。 

重要的部分是有效地处理相等传播。 我们将职位视为等价类的代表，并确保每个强制平等都与之前的分配一致。 任何矛盾都立即意味着不可能。 

### 为什么它有效

 prefix 函数完全确定数组各段之间必须存在哪些后缀-前缀重叠。 每个约束$P[i]$将一个所需的等式链精确地编码回较早的位置。 如果满足所有这些约束，则在向前重新计算时，结果数组必然会重现相同的边界结构。 该结构确保在以下位置不会引入虚假匹配：$P[i] = 0$，并且在以下情况下强制执行所有必需的匹配$P[i] > 0$。 这使得结果数组与前缀函数数组编码的唯一组合结构一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def compute_prefix(a):
    n = len(a)
    p = [0] * n
    for i in range(1, n):
        j = p[i - 1]
        while j > 0 and a[i] != a[j]:
            j = p[j - 1]
        if a[i] == a[j]:
            j += 1
        p[i] = j
    return p

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        P = list(map(int, input().split()))

        # construct candidate array
        A = [0] * n
        nxt = 1

        ok = True

        for i in range(n):
            if P[i] > 0:
                j = P[i] - 1
                if j < 0 or j >= i:
                    ok = False
                    break
                A[i] = A[j]
            else:
                if i == 0:
                    A[i] = nxt
                    nxt += 1
                else:
                    if A[i - 1] == 1:
                        A[i] = nxt
                        nxt += 1
                    else:
                        A[i] = 1

        if ok:
            if compute_prefix(A) != P:
                ok = False

        print(A if ok else -1)

if __name__ == "__main__":
    solve()
```该代码从左到右构建数组，只要前缀函数需要重复，就会重用之前分配的值。 什么时候$P[i] = 0$，它试图通过引入新的符号来避免创建意外的短边框，除非存在安全的重用。 

构建完成后，我们通过重新计算前缀函数进行验证。 最后的检查至关重要，因为局部约束并不能完全保证全局一致性。 

一个微妙的点是，相等传播是通过直接复制而不是联合查找结构隐式处理的。 这是有效的，因为每个相等总是引用一个已经构造的前缀位置，因此依赖图是非循环的并且可以一次性解析。

 ## 边缘情况

 一个关键的边缘情况是当$P[i]$超出点$i-1$。 例如，$P = [0, 2, ...]$。 在$i = 2$，我们要求长度为 2 的前缀中有长度为 2 的边界，这是不可能的，因为这意味着整个前缀与移位零的后缀匹配，这与正确的边界定义相矛盾。 该算法通过检查索引有效性立即拒绝这一点。 

另一个微妙的情况是重复的零约束。 为了$P = [0, 0, 0, 0]$，天真的重用符号可能会意外地引入意想不到的边界，例如$A[i] = A[i-1]$，创建一个非零前缀函数。 该结构通过在重用与早期强制模式匹配时引入新符号来避免这种情况，确保所有前缀根据需要保持不匹配。
