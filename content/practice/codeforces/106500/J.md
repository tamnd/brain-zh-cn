 ## 解决方案
 ## 问题理解

 比赛组织者有礼品卡，希望将其中七张礼品卡送给前七名参赛者。 将所选卡片从第一名奖品到第七名奖品进行排序后，其值必须满足两个公平规则。 一等奖的奖金与二、三等奖的奖金之和相比不能太大。 此外，前三项奖金的总和必须小于后四项奖金的总和。 在所有可能的公平选择中，我们需要所选的七张牌的总价值最大。 

输入给出可用卡的数量及其值。 输出是有效的七张牌组的最大可能总和，或者`-1`当不存在这样的组时。 

卡的数量可以多达 500000 张。这会立即排除检查所有七组的情况，因为这将需要大约$N^7$的选择，这远远超出了正常时间限制所允许的范围。 甚至$O(N^2)$对于最大输入大小来说太大。 我们需要一个接近排序复杂度的解决方案，例如$O(N \log N)$或者$O(N)$排序后。 

棘手的部分是最大的七个值并不总是答案。 一个非常大的一等奖可以打破第一个不平等，七个值的分配很重要。 例如，与：```
7
1 2 3 4 5 6 7
```唯一可能的组是所有卡片。 输出是：```
-1
```如果不小心只检查最大的七张牌的总和，则会返回 28，但最大的奖金 7 不小于 6 加 5，因此分配无效。 

当存在应忽略的超大卡片时，会出现另一种边缘情况。 为了：```
10
5 5 5 5 5 5 10 5 5 5
```答案是：```
35
```天真的贪婪方法可能会包括 10，因为它会增加总和。 但是，将所选值排序后`5 5 5 5 5 5 10`，第一个不等式变为`10 < 5 + 5`，这是错误的。 正确的解决方案是保留 10 未被使用。 

## 方法

 直接的方法是尝试每组七张卡，对这七个值进行排序，然后检查两个条件。 这是正确的，因为考虑了所有可能的答案。 问题在于可能性的数量。 从500000张牌中选择7张牌会产生大量的组合，所以这个方法无法完成。 

关键的观察结果是，有效的七人组具有非常具体的结构。 逐渐对所有卡牌值进行排序。 考虑任何有效的选择：```
a0 <= a1 <= a2 <= a3 <= a4 <= a5 <= a6
```两个中间值`a4`和`a5`分开条件。 最大值只需小于`a4 + a5`，而前四个值的总和只需大于`a4 + a5`。 

如果有效组还不是排序数组中的七个连续元素，我们可以用以相同最大选定元素结尾的更好的连续窗口替换选定元素。 每个替换值至少与旧值一样大，并且两个不等式不会变得更难以满足，因为中间和下部只会增加。 重复此转换给出的最佳答案是排序后的连续七个块。 

现在的问题是检查每个尺寸为 7 的窗口。 由于窗口大小是固定的，因此每次检查都是使用前缀和的恒定时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N^7) | O(N^7) | O(7) | 太慢了 |
 | 最佳 | O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 1. 按升序对所有卡牌值进行排序。 排序后，最佳答案可以表示为七个连续值，因此排序允许我们仅检查那些候选值。 
2. 构建排序数组的前缀和。 我们需要在扫描时快速计算任何四个或七个值组的总和。 
3. 对于每个起始索引`i`对于大小为 7 的窗口，令值为：`a[i], a[i+1], ..., a[i+6]`。 

第一个条件变为：`a[i+6] < a[i+4] + a[i+5]`。 

最大的奖品与它下面的两个奖品进行比较，因此这三个位置固定在窗口内。 
4. 检查第二个条件：`a[i+4] + a[i+5] < a[i] + a[i+1] + a[i+2] + a[i+3]`。 

后四项奖金必须超过前三项奖金。 前缀和让我们可以立即计算四元素和。 
5. 如果两个条件都成立，则用该窗口中七个值的总和更新答案。 
6. 如果没有窗口工作，则输出`-1`。 

为什么它有效：转换论证表明，最佳有效选择总是可以转移到连续的排序窗口中，而不会减少其总价值或打破不等式。 扫描会检查每种可能的最优形式，因此找到的最大有效窗口是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    pref = [0] * (n + 1)
    for i, x in enumerate(a):
        pref[i + 1] = pref[i] + x

    ans = -1

    for i in range(n - 6):
        middle = a[i + 4] + a[i + 5]

        if a[i + 6] < middle:
            first_four = pref[i + 4] - pref[i]
            if middle < first_four:
                total = pref[i + 7] - pref[i]
                if total > ans:
                    ans = total

    print(ans)

if __name__ == "__main__":
    solve()
```排序步骤按照窗口参数所需的顺序放置卡片。 排序后，无需尝试排列即可检查有效分布，因为排序顺序唯一确定了参赛者排名。 

前缀和数组存储已排序卡片的每个前缀的总和。 表达式`pref[i + 7] - pref[i]`给出完整的七张牌窗口的总和，而`pref[i + 4] - pref[i]`给出窗口内四张最小的卡片。 

循环停止于`n - 7`因为每个检查的段必须恰好包含七个元素。 不等式使用相对于窗口的索引，因此中间的一对始终是位置`i + 4`和`i + 5`。 Python 中不存在溢出问题，因为整数具有任意精度。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N log N) | O(N log N) | 排序主导单次线性扫描|
 | 空间| O(N) | 前缀和数组存储 N + 1 个值 |

 这些约束允许轻松地对 500000 个值进行排序。 排序后，每个窗口都会检查一次，因此剩余的工作是线性的。 

## 测试用例```python
import sys
import io

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    pref = [0] * (n + 1)
    for i, x in enumerate(a):
        pref[i + 1] = pref[i] + x

    ans = -1
    for i in range(n - 6):
        mid = a[i + 4] + a[i + 5]
        if a[i + 6] < mid and mid < pref[i + 4] - pref[i]:
            ans = max(ans, pref[i + 7] - pref[i])

    return str(ans)

assert solution("7\n1 2 3 4 5 6 7\n") == "-1"
assert solution("8\n1 2 3 4 5 6 7 8\n") == "35"
assert solution("10\n5 5 5 5 5 5 10 5 5 5\n") == "35"

assert solution("7\n10 1 1 1 1 1 1\n") == "-1"
assert solution("7\n1 1 1 1 1 1 1\n") == "7"
assert solution("9\n1 2 3 4 5 6 7 8 100\n") == "35"

 | --- | --- | --- |

 | 从 1 到 8 的连续值 | 35 | 35 基本有效窗口选择 |
 | 许多相等的值具有一个大值 | 35 | 35 拒绝有吸引力但无效的大奖 |
 | 一张主力牌| -1 | 第一个不平等处理 |

 ## 边缘情况

 对于这个案例：```
7
1 2 3 4 5 6 7
```该算法只有一个窗口。 中间的一对是 6 和 5，给出 11。最大值 7 满足第一个不等式，但前四个值之和为 10，不大于 11。算法拒绝窗口并打印`-1`。 

对于这个案例：```
10
5 5 5 5 5 5 10 5 5 5
```排序后的数组将 10 放在末尾。 包含它的任何窗口的最大值为 10，中间对和为 10，因此严格不等式`10 < 10`失败。 其余窗口仅包含 5 秒，有效总数为 35。 

对于这个案例：```
7
1 1 1 1 1 1 1
```所有值都是相等的。 最大值为 1，中间对的总和为 2。前四个值总和为 4，因此两个不等式都成立。 The algorithm returns the full sum, 7.
