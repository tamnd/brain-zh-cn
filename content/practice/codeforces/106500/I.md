 ## 解决方案
 ## 问题理解

 我们得到一个有向图，其中顶点表示状态，边表示从一种状态到另一种状态的一步转换。 从这个局部连通性角度来看，任务是确定完整的可达性关系：对于每个有序的顶点对，决定是否可以从第一个顶点开始并遵循有向边通过任意数量的中间步骤最终到达第二个顶点。 

输出与最短路径或计数路线无关。 这纯粹是关于路径的存在。 如果一个顶点可以通过某个循环到达自身，这也是答案的一部分，根据格式显式要求或隐式处理（通常对角线条目在传递闭包中设置为可达）。 

即使没有看到确切的限制，传递闭包问题的结构也强烈表明大小为 O(n²) 的密集关系输出。 这立即排除了尝试显式枚举所有路径的解决方案。 任何为每一对独立探索路径的方法都可以很容易地退化为 O(n3) 或更糟，这在 n 大约几千时成为边界，超出这个范围就完全不可行。 

当可达性是间接的并且需要多个跃点时，就会出现微妙的边缘情况。 例如，如果边是 1 → 2 和 2 → 3，则即使不存在直接边，也必须将 1 标记为到达 3。 简单的邻接检查会错过这一点，除非它重复传播可达性。 

另一个极端情况是自可达性。 在像 1 → 2 → 1 这样的图中，顶点 1 可以通过循环到达自身，因此闭包必须反映这一点。 任何仅标记直接边缘然后传播而不考虑循环的实现可能会错误地保留对角线条目未设置。 

## 方法

 暴力方法首先将每个顶点视为源并运行图遍历（例如 DFS 或 BFS）来标记所有可到达的节点。 这是正确的，因为每次遍历都会精确地探索从给定起点可到达的节点集。 对所有顶点重复此操作会产生完整的传递闭包。 

问题在于重复勘探成本。 单个 DFS 或 BFS 需要 O(n + m)。 对每个顶点执行此操作会导致 O(n(n + m))。 在 m 为 O(n²) 的密集图中，这变为 O(n³)。 即使图很稀疏，启动 n 个搜索的常数因子也很重要，并且 Python 实现经常在最坏情况的 CF 约束下陷入困境。 

关键的观察是可达性是传递的并且可以组合。 如果节点 i 可以到达 j，则从 j 可到达的每个节点也可以从 i 到达。 这表明我们可以逐步_传播可达节点集_，而不是独立地重新计算每个节点的可达性。 

这就是基于位集的 Floyd-Warshall 风格的想法发挥作用的地方。 我们不是单独存储布尔边，而是为每个节点存储一组可到达的节点。 当我们发现i可以到达j时，我们将j的可达集合并到i中。 这将重复的遍历变成了重复的集合并集，这在Python中可以使用整数位运算有效地实现。 

通过迭代，可达性信息通过中间节点传播，直到无法添加新位为止。 此时，每个位集都精确编码传递闭包。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 来自每个节点的强力 DFS/BFS | O(n(n + m)) | O(n(n + m)) | O(n + m) | 密集图中太慢 |
 | Bitset 传递闭包 | O(n³ / 字大小) | O(n²) | 已接受 |

 ## 算法演练

 我们将每个顶点的可达集表示为位掩码。 i的掩码中的第j位表示i是否可以到达j。 

1. 初始化一个列表`reach`， 在哪里`reach[i]`如果允许自可达性，则仅设置 i 位，并且还为每个直接边 i → j 设置位。 这将完全按照给定的方式对基本图进行编码。 
2. 迭代从 0 到 n − 1 的所有中间顶点 k。对于每个 k，我们尝试使用 k 作为其他顶点之间的桥梁。 
3. 对于每个源顶点 i，如果 i 可以到达 k，那么从 k 可以到达的所有顶点也必须可以从 i 到达。 我们更新`reach[i] = reach[i] OR reach[k]`。 这是关键的传播步骤，因为它在恒定的位集时间内将 k 的整个可达集注入到 i 中。 
4. 按升序对所有 k 重复此过程。 每次迭代允许使用最多 k 个顶点作为中间点的路径，逐渐构建越来越长的可达性链。 
5. 在所有迭代之后，根据所需的输出格式将位集解码为邻接矩阵或边列表。 

### 为什么它有效

 不变量是处理中间顶点k后，`reach[i]`包含仅使用集合 {0, 1, ..., k} 中的中间节点从 i 可到达的所有顶点。 当我们处理 k 时，我们通过附加从 k 可达的所有内容来扩展以 k 结尾的所有有效路径。 这保证了一旦处理了最高索引的中间顶点，最终就会构造出每条有效路径，并且不会引入无效路径，因为我们只传播现有的可达性集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    reach = [0] * n

    for i in range(n):
        row = input().strip()
        for j, ch in enumerate(row):
            if ch == '1':
                reach[i] |= (1 << j)

    for k in range(n):
        for i in range(n):
            if reach[i] & (1 << k):
                reach[i] |= reach[k]

    out = []
    for i in range(n):
        row = []
        for j in range(n):
            row.append('1' if (reach[i] >> j) & 1 else '0')
        out.append(''.join(row))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案读取图的邻接矩阵表示并将每一行转换为位掩码。 每个位掩码紧凑地存储从给定节点可直接到达的所有节点。 

k 和 i 上的双循环执行传递传播。 条件`reach[i] & (1 << k)`当 i 无法达到 k 时避免不必要的并集，这可以显着减少稀疏情况下的常数因子。 更新步骤将 k 的完整可达集合并到 i 中。 

最后，通过检查每个位位置将位掩码解码回二进制矩阵。 

一个常见的实现错误是忘记传播必须在_已经更新的_范围集上完成。 k 循环的顺序很重要，因为它确保逐渐引入中间节点作为有效的垫脚石。 

## 工作示例

 考虑一个具有三个节点和边 0 → 1 和 1 → 2 的图。 

### 初始状态

 | 我| 到达[i]（二进制）|
 | --- | --- |
 | 0 | 010|
 | 1 | 001|
 | 2 | 000 | 000

 处理 k = 0 后，没有任何变化，因为除了它自己之外没有节点达到 0。 

处理完 k = 1 后，节点 0 达到 1，并且由于 1 达到 2，因此我们将 2 传播到 0。 

| 步骤| 我| 到达[i] |
 | --- | --- | --- |
 | k=1 传播 | 0 | 011|
 | k=1 传播 | 1 | 001|
 | k=1 传播 | 2 | 000 | 000

 k = 2 之后，不再发生进一步的更新。 

最终结果显示0同时达到1和2，而1达到2。 

该跟踪演示了仅在中间顶点作为桥激活后如何累积间接可达性。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n3 / w) | 每次 n 次迭代都使用字级 OR 运算传播 n 个位集 |

 立方结构与闭包计算的固有性质相匹配，但位运算显着压缩了常数因子。 这足以满足竞争性编程环境中多达数千个节点的典型约束。

 ## 边缘情况

 在三节点链 0 → 1 → 2 中，简单的单遍更新可能会在标记 0 → 1 和 1 → 2 后停止，但无法传播 0 → 2。正确的算法会处理此问题，因为当处理 k = 1 时，reach[0] 已经包含 1，因此它会吸收包含 2 的reach[1]。 

在循环 0 → 1 → 2 → 0 中，每个节点最终都会到达其他每个节点。 在迭代 k = 0 期间，节点 2 已经可以间接到达 0，当 k = 0 用作中间时，它将其完整集合传播回 2，完成闭包。 这种反馈循环自然是通过重复的联合传播而不是显式循环检测来解决的。
