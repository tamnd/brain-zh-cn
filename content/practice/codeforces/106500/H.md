 ## 解决方案
 # 问题理解

 该游戏在一维单元格上进行。 最初每个单元格都是空的。 玩家轮流选择一个空位并在那里放置十字。 仅当生成的条带不包含三个连续的交叉时才允许移动。 无法采取行动的玩家就输了。 

该程序不会被要求打印最终获胜者。 它必须与法官进行游戏。 在游戏开始之前，它会选择先走还是后走。 此后，它必须始终采取确保胜利的行动。 

条带长度最多为 30。这个界限足够小，我们可以将整个棋盘表示为位掩码并搜索游戏状态。 理论上，30 的长度最多给出 2^30 个可能的掩码，这对于盲目访问来说太多了，但禁止三个连续交叉的规则大大减少了可达状态的数量。 不带二进制串的个数`111`像 tribonacci 序列一样增长，并且足够小，可以在此限制下进行记忆搜索。 

主要边缘情况来自靠近条带末端的位置以及移动创建一对相邻交叉的位置。 

对于长度为 1 的条带，唯一的移动就是占据单个单元格。 输入是：```
1
```正确的行为是选择首先移动并玩单元 1。总是尝试进行“中间”移动的策略将会失败，因为不需要中间处理。 

第二个边缘情况是看似局部有效但会产生三个交叉的棋步。 例如，在长度为 3 的条带上：```
XXX
```玩家无法进行任何动作。 一个粗心的实现，仅检查所选单元格是否为空，将允许非法移动。 

另一个重要的情况是当条带包含两个连续的十字时：```
XX..
```无法填充下一个单元格，因为它会创建`XXX`，但距离较远的单元格仍然是合法的。 合法性检查必须检查整个董事会，而不仅仅是所选职位。 

## 方法

 一种直接的方法是模拟完整的博弈树。 对于每个位置，尝试每一个合法的动作，递归地解决结果位置，如果至少有一个动作使对手处于失败状态，则将当前状态标记为获胜。 这正是公正游戏中获胜位置的定义。 

在没有记忆的情况下，它会探索每一个可能的动作序列。 深度可以达到 30，分支因子也可以接近 30，给出 30 左右不切实际的上限！ 的可能性。 

关键的观察结果是到达董事会位置的顺序并不重要。 具有相同占据单元的棋盘总是具有相同的未来移动。 我们可以存储每个访问过的掩码的结果。 可达掩码的数量远小于 2^30，因为包含以下内容的无效掩码`111`永远不会出现。 记忆化将重复的博弈树变成了图的遍历。 

同样的递归函数也可以返回实际获胜的棋步。 当法官采取行动时，我们更新掩码并再次向函数询问使对手处于失败状态的行动。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 最坏情况下为 O(30!) | O(30) 递归深度 | 太慢了 |
 | 最佳 | O(S × 30)，其中 S 是可达有效状态的数量 | O(S)| 已接受 |

 ## 算法演练

 1.读取条带长度，判断初始位置是否获胜。 递归求解器检查空棋盘是否有迫使对手失败的棋步。 如果是，程序选择先移动。 否则，它选择第二个移动。 
2. 将当前棋盘表示为整数掩码。 少量`i`为 1，当细胞`i`已经包含一个十字架。 这提供了恒定的时间更新，并允许将完整的状态用作记忆密钥。 
3. 对于一个状态，尝试每个空单元格。 暂时在此处打叉，检查棋盘是否仍然遵循不设置连续三个位的规则。 
4. 如果对手的合法棋步达到了失败状态，则将此棋步存储为当前状态的获胜棋步。 如果不存在这样的移动，则将该状态标记为失败。 
5. 在游戏过程中，每当对手做出一步棋时，将该单元格添加到掩码中并查询存储的获胜棋步。 输出该单元格并继续，直到法官结束游戏。 

为什么它有效：

 递归定义遵循标准的赢和输国家财产。 当一个州至少有一次向失败州移动时，它就赢了。 当每一个合法的举动都给对手一个获胜的状态时，一个状态就输了。 由于每一步都会增加一个十字，游戏图表没有循环，因此记忆永远不会产生歧义。 储存的棋步总是会导致对手无法强行取胜。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from functools import lru_cache

def solve_game(n):
    @lru_cache(None)
    def dfs(mask):
        for i in range(n):
            if mask >> i & 1:
                continue
            nxt = mask | (1 << i)
            if not valid(nxt):
                continue
            if dfs(nxt) == -1:
                return i
        return -1

    @lru_cache(None)
    def valid(mask):
        cnt = 0
        for i in range(n):
            if mask >> i & 1:
                cnt += 1
                if cnt >= 3:
                    return False
            else:
                cnt = 0
        return True

    return dfs

def main():
    n = int(input())

    dfs = solve_game(n)
    mask = 0

    first_move = dfs(mask)

    if first_move != -1:
        print(1)
        print(first_move + 1)
        sys.stdout.flush()
        mask |= 1 << first_move
    else:
        print(2)
        sys.stdout.flush()

    while True:
        x = int(input())
        if x == 0:
            return

        mask |= 1 << (x - 1)

        move = dfs(mask)
        if move == -1:
            print(0)
            sys.stdout.flush()
            return

        print(move + 1)
        sys.stdout.flush()
        mask |= 1 << move

if __name__ == "__main__":
    main()
```这`dfs`function 是完整的游戏求解器。 它返回一个州的获胜棋步指数，并且`-1`当国家正在失败的时候。 递归仅探索通过合法移动可到达的状态。 

这`valid`函数检查游戏的唯一规则。 它扫描连续占用的单元并拒绝任何长度为三的游程。 将其分开可以避免生成动作时出现细微的错误。 

每次移动后都会立即更新掩码。 这使存储的状态与实际板保持同步。 输出使用基于 1 的索引，因为交互协议从 1 开始对单元格进行编号。 

递归深度最多为30，因此Python默认的递归限制就足够了。 缓存状态的数量是限制因素，而不是递归深度。

## 测试用例

 最初的问题是交互式的，因此传统的基于断言的测试并不直接适用。 核心游戏解算器仍然可以通过检查返回的移动分类是否与已知位置匹配来测试。```
from functools import lru_cache

def make_solver(n):
    @lru_cache(None)
    def valid(mask):
        run = 0
        for i in range(n):
            if mask >> i & 1:
                run += 1
                if run == 3:
                    return False
            else:
                run = 0
        return True

    @lru_cache(None)
    def win(mask):
        for i in range(n):
            if mask >> i & 1 == 0:
                nxt = mask | (1 << i)
                if valid(nxt) and not win(nxt):
                    return True
        return False

    return win

assert make_solver(1)(0) is True
assert make_solver(3)(0) is True
assert make_solver(3)(7) is False
assert make_solver(5)(0) in (True, False)
```| 测试输入| 预期产出 | 它验证了什么 |

 | 长度3空条| 胜利状态| 小游戏搜索|

 ## 边缘情况

 对于单单元条带，求解器从掩模开始`0`。 它尝试细胞`0`，达到掩模`1`，且见对方无招。 位置获胜，因此程序选择先移动。 

对于职位`XX..`，掩模包含两个相邻的十字。 当检查下一个单元格时，生成的掩码包含`XXX`， 所以`valid`拒绝它。 求解器仍然考虑更远的单元格并且可以正确地继续游戏。 

对于完全阻塞的位置，例如`XXX`，每个可能的位都已设置，无法生成任何移动。 递归函数返回`-1`，将状态标记为失败。 这正是游戏所要求的终止条件。
