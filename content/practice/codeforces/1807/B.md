[CF 1807B - 抢糖果](https://codeforces.com/problemset/problem/1807/B)

 **标签：** 贪婪
 **求解时间：** 1m 26s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们有几袋糖果。 装有偶数糖果的袋子总是给 Mihai，而装有奇数糖果的袋子总是给 Bianca。 

袋子的顺序不固定。 在比赛开始前，我们可以按照自己的意愿重新排列它们。 当袋子从左到右处理时，每个玩家都会从收到的袋子中积累糖果。 

目标是确定是否存在某种排序，使得在每个处理过的袋子之后（游戏开始前除外），Mihai 的糖果总数严格大于 Bianca 的总数。 

限制非常小。 每个测试用例最多有100个包，最多有1000个测试用例。 甚至一个$O(n^2)$解决方案很容易足够快。 挑战不在于效率，而在于识别决定是否存在有效排序的属性。 

一个常见的错误是通过构建显式排序来专注于在每一步之后维持不平等。 例如：```
1
4
1 2 3 4
```贪心模拟可以找到一个排序，但问题只问是否存在一个排序。 还有一个更简单的条件。 

另一种微妙的情况是只有一个偶数袋时：```
1
4
1 1 1 2
```偶数糖果总数为$2$，而奇数糖果总数为$3$。 米哈伊不可能永远保持领先，因为比安卡的总成绩最终超过了米哈伊。 正确答案是`NO`。 

第三种边缘情况是所有包都是奇数时：```
1
3
1 3 5
```第一个处理过的袋子必须交给 Bianca，使 Mihai 的总数达到$0$比安卡呈阳性。 所需的不等式立即失效。 正确答案是`NO`。 

最后，考虑：```
1
3
2 2 1
```偶数总和是$4$奇数和是$1$。 正确答案是`YES`。 如果粗心地只检查最大偶数值和最大奇数值，就会错过这一点。 

## 方法

 最直接的暴力想法是尝试每一种可能的袋子排列并模拟游戏。 对于每个排列，我们逐个处理袋子，更新 Mihai 和 Bianca 的总数，并检查 Mihai 是否在每一步后都保持严格领先。 

这种方法是正确的，因为它检查了每种可能的顺序。 问题是有$n!$排列。 即使是为了$n = 10$，这已经是大约 360 万种排列。 为了$n = 100$，这是完全不可能的。 

为了找到更好的解决方案，我们需要了解真正重要的是什么。 

假设我们首先放置所有偶数袋。 每一件袋子只会增加米海的总数。 这显然是建立优势的最佳方式。 处理完所有偶数行李后，Mihai 已收集到所有偶数行李，而 Bianca 仍然没有收集到任何东西。 

现在，零散的袋子可以按任何顺序进行处理。 每个奇怪的袋子只会增加比安卡的总数。 米哈伊的总数再也没有改变过。 

这一观察至关重要。 如果所有偶数袋的总和大于所有奇数袋的总和，则在先处理完所有偶数袋后，Mihai 以大于比安卡最终总和的领先优势开始奇数阶段。 比安卡永远无法追上，因此每个中间状态也是安全的。 

如果偶数袋的总和小于或等于奇数袋的总和，那么在整个过程结束时，Mihai 的总和并不严格大于 Bianca 的总和。 由于要求在每一步之后都必须成立，因此在最后一步之后它当然也必须成立。 这样的顺序不可能存在。 

整个问题简化为比较两个和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n! \cdot n)$|$O(n)$| 太慢了|
 | 最佳 |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 对于测试用例，初始化两个变量：`even_sum`和`odd_sum`。 
2. 遍历所有包。 
3. 如果袋子里有偶数个糖果，则将其价值添加到`even_sum`。 
4. 否则，将其值添加到`odd_sum`。 
5. 处理完所有袋子后，比较两个总数。 
6. 如果`even_sum > odd_sum`， 打印`YES`。 
7. 否则，打印`NO`。 

为什么它有效：

 无论排序如何，最终总数都是固定的。 Mihai 总是以所有偶数包的总和结束，而 Bianca 总是以所有奇数包的总和结束。 

如果`even_sum <= odd_sum`，所需的不等式在最终状态下已经失败，因此任何排序都不起作用。 

如果`even_sum > odd_sum`，将每个偶数袋放在每个奇数袋之前。 在第一阶段，比安卡的总数保持为零，而米哈伊的总数则增加。 在第二阶段，Mihai 的总数保持等于`even_sum`，比安卡的运行总数从未超过`odd_sum`。 自从`even_sum > odd_sum`整个过程中，米海始终保持领先。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    even_sum = 0
    odd_sum = 0

    for x in a:
        if x % 2 == 0:
            even_sum += x
        else:
            odd_sum += x

    print("YES" if even_sum > odd_sum else "NO")
```解法直接遵循证明。 

该循环根据奇偶校验将所有包值分为两组。`even_sum`代表 Mihai 最终的总数，而`odd_sum`代表比安卡的最终总数。 

处理完所有值后，只需要进行一次比较。 严格的不平等很重要。 使用`>=`是错误的，因为该声明要求 Mihai 在每个有效时刻（包括最终状态）严格拥有更多糖果。 

对于空奇偶校验组不需要特殊处理。 如果连袋子都没有的话，`even_sum`变为零，比较自然会产生正确的结果。

## 测试用例```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        even_sum = sum(x for x in a if x % 2 == 0)
        odd_sum = sum(x for x in a if x % 2 == 1)

        ans.append("YES" if even_sum > odd_sum else "NO")

    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

 ## 边缘情况

 ### 所有包都是奇怪的

 输入：```
1
3
1 3 5
```该算法计算：

 | 偶数总和 | 奇数总和 |
 | --- | --- |
 | 0 | 9 |

 自从`0 > 9`是假的，它打印`NO`。 

这符合现实。 第一个处理的包必须交给 Bianca，因此 Mihai 在第一步后不能严格领先。 

### 总数相等

 输入：```
1
2
1 1
```该算法计算：

 | 偶数总和 | 奇数总和 |
 | --- | --- |
 | 0 | 2 |

 答案是`NO`。 

更一般地说，只要两个总数相等，最终状态就会是米哈伊和比安卡并列。 条件要求米海严格领先，所以不能接受平等。 

### 只有一个偶数袋

 输入：```
1
4
1 1 1 2
```该算法计算：

 | 偶数总和 | 奇数总和 |
 | --- | --- |
 | 2 | 3 |

 答案是`NO`。 

即使先放入装有 2 颗糖果的袋子，Mihai 最终可能的最大总数仍然只有 2。Bianca 最终达到 3，因此所需的不等式不能维持到最后。 

### 大平优势

 输入：```
1
3
2 2 1
```该算法计算：

 | 偶数总和 | 奇数总和 |
 | --- | --- |
 | 4 | 1 |

 答案是`YES`。 

首先放置均匀的袋子：`[2, 2, 1]`。 

处理袋子后，运行总计为：

 | 步骤| 米海| 比安卡 |
 | --- | --- | --- |
 | 2 之后 | 2 | 0 |
 | 2 之后 | 4 | 0 |
 | 1 之后 | 4 | 1 |

 米哈伊自始至终都严格领先，正如情况所预测的那样`even_sum > odd_sum`。
