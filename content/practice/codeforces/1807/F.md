 ## 解决方案
 ## 问题理解

 我们有一个球在里面移动`n × m`矩形网格。 球总是沿对角线移动，因此每次移动都会改变两个坐标`±1`。 

方向由垂直分量和水平分量组成。 例如，`DR`意味着同时增加行和列，而`UL`意味着两者都减少。 每当下一步移动离开网格时，方向的相应分量就会反转。 击中顶部或底部墙壁会翻转垂直组件。 击中左侧或右侧墙壁会翻转水平分量。 到达角落时，两者都会翻转。 

任务不是数步数。 我们必须计算球第一次到达目标单元格之前发生了多少次弹跳。 如果球从未到达该单元格，我们输出`-1`。 

最重要的约束是所有测试用例的所有网格大小的总和最多为`5 · 10^4`。 这是令人惊讶的小。 尽管个别尺寸可以达到`25000`，所有测试用例的单元总数是有限的。 这强烈表明，如果我们避免无限期地重新访问相同的状态，则模拟运动是可行的。 

一个微妙的点是球进入单元格后会弹跳。 在方向改变之前访问单元本身。 任何先反映然后检查位置的模拟都可能产生错误的答案。 

另一个微妙之处是球可能会进入一个不包含目标细胞的循环。 由于运动是确定性的，一旦相同的状态再次出现，未来就会永远重复。 

考虑：```
2 4
start = (2,1), DR
target = (2,2)
```球移动：```
(2,1) -> (1,2) -> (2,3) -> (1,4) -> ...
```细胞`(2,2)`从未被访问过。 没有循环检测的模拟将永远运行。 正确答案是`-1`。 

Another easy mistake is counting bounces instead of counting bounces before reaching the target.

 例子：```
3 3
start = (1,3), UR
target = (2,2)
```球首先到达`(2,2)`从上壁弹起一次后。 答案是`1`。 如果我们继续模拟并计算后来的反弹，结果就会变得不正确。 

当起始位置已经等于目标位置时，会出现第三种极端情况。 

例子：```
3 3
start = (2,2), DR
target = (2,2)
```答案是`0`因为在任何运动发生之前球就已经在那里了。 

## 方法

 简单的模拟一次一步地跟踪球。 每次移动时，我们都会更新位置，执行任何必要的反射，并计算反弹次数。 

这种方法是正确的，因为运动规则是确定性的。 问题是球在重复之前可能会移动很长时间。 由于尺寸可以大到`25000`，纯粹的逐步模拟可能需要数百万次移动。 

关键的观察是反弹之间没有发生任何有趣的事情。 

假设球当前位于`(r,c)`有一定的方向。 在撞到墙壁之前，它只是沿着直线对角线移动。 在该段期间，行和列每一步的变化量相同。 

我们可以直接跳到下一个弹跳，而不是模拟每一个动作。 让```
dr ∈ {+1,-1}
dc ∈ {+1,-1}
```代表当前方向。 

到下一个垂直墙的距离由下式确定`dr`:```
if dr = +1: n - r
if dr = -1: r - 1
```同样，到下一个水平墙的距离为：```
if dc = +1: m - c
if dc = -1: c - 1
```这两个距离中较小的一个告诉我们在下一次反弹事件之前还剩多少对角线步数。 

当沿着该对角线段行进时，当行偏移和列偏移匹配时就准确地到达目标。 我们可以用代数方法测试这一点，而无需逐步遍历每个中间单元。 

跳转到弹跳位置后，我们翻转所需的方向分量，增加弹跳计数器，然后继续。 

系统的状态是：```
(row, column, direction)
```只有`4nm`可能的状态。 一旦一个状态重复，未来的轨迹也会重复。 自从总共`nm`所有测试最多是`5 · 10^4`，存储访问过的状态很容易负担得起。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(移动次数) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(弹跳态数) ≤ O(nm) | O(纳米) | 已接受 |

 ## 算法演练

 1. 将方向字符串转换为两个分量`dr`和`dc`，每一个都等于`+1`或者`-1`。 
2. 如果起始单元格已经等于目标单元格，则返回`0`。 
3. 维护一组访问过的状态`(row, column, dr, dc)`。 
4. 在处理一个状态之前，检查它是否已经被看到。 如果有，则轨迹已进入循环，永远无法达到目标。 返回`-1`。 
5. 计算直到下一个垂直墙和下一个水平墙的步数。 
6.让`k`是这两个值中较小的一个。 球准确地行进`k`下一个反弹事件之前的对角线步骤。 
7. 检查目标是否位于该对角线段上。 由于两个坐标都线性移动，因此在段 iff 期间达到目标：

 -`(i2 - row)`具有相同的符号`dr`,
 -`(j2 - col)`具有相同的符号`dc`,
 - 并且所需的行和列偏移量相等。 

如果目标位于下一个`k`步骤，返回当前的跳出计数。 
8. 将球直接移动到弹跳位置：```
row += dr * k
col += dc * k
```9. 如果弹跳位置位于上边框或下边框，则翻转`dr`。 
10. 如果弹跳位置位于左边框或右边框，则翻转`dc`。 
11. 将跳出计数增加 1，然后从步骤 4 继续。 

### 为什么它有效

 在两次连续弹跳之间，球遵循一条直线对角线。 该段上访问的每个单元格都满足行偏移和列偏移之间的固定线性关系。 检查目标是否属于该段足以确定在下一次反弹之前是否会达到它。 

模拟始终从一个弹跳状态跳转到下一个弹跳状态，而不会跳过任何可能的目标出现，因为每个中间位置都位于检查的对角线段上。 

运动是确定性的。 一旦成为一个州`(row, column, dr, dc)`重复，所有未来状态也会重复。 如果在重复之前没有找到目标，那么以后就再也找不到了。 这保证了返回`-1`在重复状态上是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

DIR = {
    "DR": (1, 1),
    "DL": (1, -1),
    "UR": (-1, 1),
    "UL": (-1, -1),
}

def solve():
    t = int(input())

    for _ in range(t):
        n, m, r, c, tr, tc, d = input().split()

        n = int(n)
        m = int(m)
        r = int(r)
        c = int(c)
        tr = int(tr)
        tc = int(tc)

        dr, dc = DIR[d]

        if r == tr and c == tc:
            print(0)
            continue

        visited = set()
        bounces = 0
        answer = -1

        while True:
            state = (r, c, dr, dc)

            if state in visited:
                break

            visited.add(state)

            dv = (n - r) if dr == 1 else (r - 1)
            dh = (m - c) if dc == 1 else (c - 1)

            k = min(dv, dh)

            row_diff = tr - r
            col_diff = tc - c

            if row_diff * dr >= 0 and col_diff * dc >= 0:
                if row_diff == col_diff * dr * dc:
                    steps = abs(row_diff)
                    if steps <= k:
                        answer = bounces
                        break

            r += dr * k
            c += dc * k

            bounced = False

            if r == 1 or r == n:
                dr *= -1
                bounced = True

            if c == 1 or c == m:
                dc *= -1
                bounced = True

            if bounced:
                bounces += 1

        print(answer)

solve()
```方向字符串被转换为两个带符号的分量。 这使得反射变得非常简单，因为从水平墙上反射只会改变`dr`，而从垂直墙上弹跳只会改变`dc`。 

核心思想是跳跃长度`k`。 我们不是模拟每一个动作，而是计算球在接触墙壁之前可以移动多远。 整个对角线段被立即处理。 

目标检查是最微妙的部分。 沿着对角线段，两个坐标的幅度变化完全相同。 平等```
row_diff == col_diff * dr * dc
```同时编码所有四个方向的要求。 

另一个微妙的细节是跳出计数的时间。 我们首先检查目标是否位于当前段上。 如果是这样，答案就是已经发生的退回次数。 只有到达反弹位置后，我们才会增加反弹计数器。 

循环检测使用完整状态`(row, column, dr, dc)`。 仅使用位置是不正确的，因为以不同的方向到达同一单元可能会导致不同的未来轨迹。

 ## 边缘情况

 ### 起始位置已经是目标

 输入：```
1
3 3 2 2 2 2 DR
```该算法在进入模拟循环之前检查此条件。 不需要移动，因此输出：```
0
```如果没有此检查，模拟将继续移动并可能返回更大的值。 

### 目标永远不会出现在循环中

 输入：```
1
2 4 2 1 2 2 DR
```痕迹：```
(2,1,DR)
→ (1,2,UR)
→ (2,3,DR)
→ (1,4,UR)
→ (2,3,DL)
→ ...
```最终，先前看到的状态再次出现。 目标`(2,2)`从未属于任何已处理的对角线段，因此算法返回：```
-1
```重复状态检查可防止无限循环。 

### 恰好在段末尾达到目标

 输入：```
1
6 4 1 2 3 4 DR
```第一个对角线段的长度`k = 2`:```
(1,2) → (2,3) → (3,4)
```目标是该段的最后一个单元格。 由于目标检查使用`steps <= k`，包含端点并且算法正确输出：```
0
```使用严格的不等式会错误地错过这种情况。 

### 角球弹跳

 输入：```
1
2 2 1 1 1 2 UL
```球开始的方向`UL`，立即到达拐角处`(1,1)`弹跳状态，在处理拐角时两个方向分量一起反转。 

如果触摸顶部或底部边框，则该实现将翻转垂直分量；如果触摸左边框或右边框，则独立翻转水平分量。 一个角自然会触发两次翻转，完全符合问题规则。
