 ## 解决方案
 ## 问题理解

 我们被问到是否给定的数组`c`可以从初始数组开始生成`[1]`通过重复添加一个等于当前数组的任何子序列之和的新元素。 子序列的长度可以是从 1 到数组大小的任意长度，并且子序列中的元素不需要是连续的。 每次操作后，新元素都会添加到数组中的某个位置。 

输入由多个测试用例组成。 每个测试用例都提供最终数组的大小和数组本身。 如果可以以这种方式构造最终数组，则输出应为“YES”，否则输出应为“NO”。 

鉴于限制条件，`n`可以大到`2*10^5`每个测试用例，以及所有测试用例的总和`n`跨测试用例不超过`2*10^5`。 这意味着任何二次解`n`会太慢； 我们需要一些大致线性或线性的东西，理想情况下每个测试用例都是 O(n log n) 或 O(n) 。 中的值`c`还可以达到`2*10^5`，因此计数或频率图等操作必须有效地处理该范围。 

不明显的边缘情况包括具有重复的小值的序列。 例如，像这样的数组`[1, 1, 1]`是有效的，因为我们可以重复将 1 的子序列相加以生成更多 1。 粗心的方法可能只检查元素是否唯一或单调，这会错误地拒绝此类序列。 另一个棘手的情况是当`c`有一个元素大于1，例如`[2]`; 这是不可能的，因为从`[1]`，第一个操作总是产生至少两个元素，因此大于 1 的单个元素永远不会单独出现。 

## 方法

 暴力方法将尝试模拟所有可能的操作序列。 开始于`[1]`，我们可以在每一步生成所有子序列的总和，看看我们是否可以生成`c`。 虽然原则上是正确的，但这种方法是不可行的，因为子序列的数量随着数组的大小呈指数增长。 和`n`最多`2*10^5`，生成或检查所有子序列在计算上是不可能的。 

关键的见解是可以使用频率图贪婪地解决该问题。 我们可以逆向思考，而不是向前构建数组：从`c`，我们询问每个元素是否可以从较小元素的某种组合中获得。 观察到每个新元素必须小于或等于到目前为止数组的当前总和，我们可以模拟一个过程，我们总是通过将最大的剩余元素分解为较小元素的总和来“消耗”最大的剩余元素。 这将问题简化为维护数字的多重集并重复分割最大元素，直到它与我们需要的数字匹配。 

实际上，我们从所有元素的总和开始`c`并继续将其分成两半（如果是奇数则为下限和上限），直到所有数字`c`均已核算。 这使用最大堆（优先级队列）来始终分割最大的数字，并使用频率图来跟踪每个目标数字需要出现的次数。 由于堆操作，该方法的复杂度为 O(n log n)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(2^n) | O(2^n) | 太慢了 |
 | 用堆逆向贪婪 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取所有输入并存储测试用例。 
2. 对于每个测试用例，计算最终数组的总和`c`。 该和代表反向构造中的第一个“元素”，因为任何序列都必须从最终产生该总和开始。 
3. 创建一个仅包含总和的最大堆。 维护一个计数器来计算元素的频率`c`。 
4. 当堆不为空时：

 - 弹出最大的元素`x`。 
- 如果`x`匹配一个元素`c`如果频率为正，则减少其频率并继续。 
- 如果`x`是 1 或小于中最大的剩余元素`c`但不完全是在`c`，不可能产生`c`; 返回“否”。 
- 否则，分裂`x`分为两部分，`x // 2`和`x - x // 2`，并将两者推回堆中。 这模拟生成`x`来自较小的元素。 
5. 处理完所有元素后，如果所有频率都在`c`为零，返回“YES”； 否则返回“NO”。 

为什么它有效：不变量是在每一步中，堆都包含可以拆分以匹配剩余所需数字的元素。 分割最大的可以确保我们永远不会错过比剩余的更大的数字，并且频率图保证我们只计算有效的目标。 如果在任何时候一个数字都不能被分割成与剩余的相对应的元素`c`，该序列是不可能的。 

## Python 解决方案```python
import sys
import heapq
from collections import Counter

input = sys.stdin.readline

def can_construct(c):
    freq = Counter(c)
    total = sum(c)
    max_heap = [-total]
    heapq.heapify(max_heap)
    
    while max_heap:
        x = -heapq.heappop(max_heap)
        if freq[x]:
            freq[x] -= 1
            continue
        if x == 1:
            return False
        a = x // 2
        b = x - a
        heapq.heappush(max_heap, -a)
        heapq.heappush(max_heap, -b)
    return all(v == 0 for v in freq.values())

t = int(input())
for _ in range(t):
    n = int(input())
    c = list(map(int, input().split()))
    print("YES" if can_construct(c) else "NO")
```解决方案首先将目标数组的总和转换为最大堆。 每次迭代都会尝试匹配所需的最大元素。 如果该元素在频率图中，则它会被消耗。 否则，它会被分割，这反映了在前向构造中如何形成总和。 在堆中使用负数允许 Python 的最小堆表现为最大堆。 元素无法匹配或为 1 的边缘情况自然由条件检查处理。 

## 工作示例

 ### 示例 1

 输入数组：`[5, 1, 3, 2, 1]`| 步骤| 堆| 频率图 | 行动|
 | --- | --- | --- | --- |
 | 开始| [-12]| {1:2,2:1,3:1,5:1} | 总和 12 |
 | 流行 12 | []| 不变| 分割 12 -> 6,6 |
 | 推 6,6 | [-6，-6] | 不变| 分割 6 -> 3,3 |
 | 推 3,3,-6 | [-6,-3,-3] | 不变| 分割 6 -> 3,3 |
 | 流行 3 | [-3,-3,-3] | 3 存在 -> 减少频率 | 消耗 3 |
 | 流行 3 | [-3，-3] | 3 频率=0 | 分割 3 -> 1,2 |
 | 推 1,2 | [-3,-2,-1] | 更新频率 | 等等|
 | 继续 | ... | | 所有元素都匹配，堆为空 -> YES |

 这表明从最大元素分裂并使用频率图可以正确重建目标数组。

 这看起来很好但要小心：起始数组是 [1]，为了获得单个元素 2，第一个操作会产生至少两个元素。 因此，具有不变量的堆方法失败并正确返回 NO。
