[CF 1950E - 几乎最短的重复子串](https://codeforces.com/problemset/problem/1950/E)

 **评分：** 1500
 **标签：** 暴力破解、实现、数论、字符串
 **求解时间：** 1m 22s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们得到一个字符串`s`长度`n`。 我们想要找到尽可能小的长度`L`使得存在一个模式字符串`k`长度`L`, 完全重复`n / L`次，产生一个字符串`c`长度`n`， 和`c`不同于`s`至多处于一个位置。 

换句话说，最多改变一个字符后`s`，所得字符串必须具有周期长度的完美周期性`L`。 在所有有效期限中，我们需要最短的一个。 

该语句的关键观察结果是重复字符串必须覆盖整个字符串长度，因此候选周期长度必须除以`n`。 

所有测试用例的总长度最多为`2 · 10^5`。 这个值足够大，以至于天真地将每个可能的模式与每个可能的子字符串进行比较可能会变得昂贵。 一个算法围绕`O(n · d(n))`， 在哪里`d(n)`是除数的数量，是完全安全的，因为即使是下面最大的数字`2 · 10^5`因数相对较少。 一个`O(n²)`在最坏的情况下，方法太慢。 

一些边缘情况很容易被错误处理。 

考虑：```
n = 4
s = abaa
```答案是`1`， 因为`"aaaa"`恰好有一个位置不同。 仅检查原始字符串是否已经是周期性的解决方案会错误地拒绝周期`1`。 

考虑：```
n = 4
s = abba
```答案是`4`。 两个时期都没有`1`也不期`2`可以通过单个字符更改来修复。 贪婪地选择每个残基类中最常见的字符的解决方案可能会错误地得出该时期的结论`2`作品。 

考虑：```
n = 6
s = aaabaa
```答案是`1`。 该字符串不同于`"aaaaaa"`恰好在一个位置。 这种情况表明，单个坏字符可能出现在任何地方，不一定出现在第一个句点块内。 

另一个微妙的情况是：```
n = 8
s = ababcbab
```时期`2`不起作用。 不匹配出现在涉及相同错误字符的多次比较中。 计算成对的分歧而不是计算实际的字符变化可能会高估所需的修改。 

## 方法

 自然的暴力方法是尝试每个除数`L`的`n`，生成每个可能长度的周期字符串`L`，并检查重复是否匹配`s`至多有一个不匹配。 

问题是可能的句点字符串数量呈指数级增长。 甚至将我们限制为出现在内部的句点字符串`s`并不能立即提供帮助。 搜索空间变得巨大。 

我们需要利用只有一个字符可能是错误的这一事实。 

假设我们固定候选周期长度`L`。 每个位置`i`属于残留类`i mod L`。 在完美周期字符串中，同一残基类中的所有字符必须相等。 

例如，与`L = 3`:```
positions: 0 1 2 3 4 5 6 7 8
residues : 0 1 2 0 1 2 0 1 2
```每个残基类别必须包含单个重复字符。 

如果整个字符串最多可以通过一次修改来修复，那么在按残基类别对位置进行分组之后，除了可能的一个位置之外的所有位置都已经与最终的周期模式一致。 

关键的观察是，如果最多有一个字符是错误的，那么正确的句点字符串必须等于现有长度块之一`L`。 

为什么？ 

假设最终的周期字符串使用句点`k`。 由于整个字符串中只有一个位置是错误的，因此除了可能的一个之外，每个块都与`k`。 因此，原始字符串的某些块必须已经相等`k`。 

这立即减少了搜索空间。 对于固定除数`L`，我们只需要测试从现有长度块中获取的候选周期`L`。 

有`n / L`块。 天真地测试所有这些代码的成本太高，但由于只有一个块可以包含错误字符，因此检查前两个块就足够了。 

如果存在有效周期，则所有正确的块都等于真实周期。 最多有一个块不同。 前两个块中，至少有一个必须是正确的。 

所以对于每个除数`L`，我们测试：```
candidate = first block
candidate = second block (if it exists)
```对于每个候选者，我们将重复模式与整个字符串进行比较并计算不匹配的数量。 如果不匹配数最多为 1，则`L`是有效的。 

这将问题转化为检查每个除数的少数候选者。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 周期长度呈指数 | O(L) | 太慢了 |
 | 最佳 | O(n·d(n)) | O(n·d(n)) | O(L) | 已接受 |

 ## 算法演练

 1. 枚举所有除数`L`的`n`按递增顺序。 
2. 对于每个除数，将字符串分割成长度的块`L`。 
3. 使用第一个块构建候选周期。 
4. 将重复的候选者与整个字符串进行比较并计算不匹配的数量。 
5. 如果不匹配次数最多为1，则返回`L`立即，因为除数是按升序处理的。 
6.否则，如果存在多个块，则使用第二块构造第二候选。 
7. 将第二个候选与整个字符串进行比较。 
8. 如果不匹配次数最多为1，则返回`L`。 
9. 继续计算下一个除数。 
10. 如果没有更小的除数，`L = n`总是有效，因为字符串本身可以用作句点。 

### 为什么它有效

 假设一些除数`L`是有效的。 让`k`为修复后弦的真实周期。 

由于整个字符串中可能只有一个字符是错误的，因此最多有一个块的长度`L`不同于`k`。 其他每个块都完全等于`k`。 

在前两个块中，至少有一个不能是损坏的块。 因此至少其中一个等于真实周期`k`。 

当算法测试该块作为候选时，重复的候选正是修复后的字符串。 它与原始字符串的不匹配计数最多为 1，因此算法接受`L`。 

相反，如果算法接受一个候选者，那么重复该候选者会产生一个不同于`s`至多处于一个位置。 这正是问题所需要的条件。 

由于除数是按升序处理的，因此第一个接受的除数是最小可能的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def works(s, n, d, pat):
    mism = 0
    for i in range(n):
        if s[i] != pat[i % d]:
            mism += 1
            if mism > 1:
                return False
    return True

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        s = input().strip()

        divisors = []
        i = 1
        while i * i <= n:
            if n % i == 0:
                divisors.append(i)
                if i * i != n:
                    divisors.append(n // i)
            i += 1

        divisors.sort()

        answer = n

        for d in divisors:
            block_cnt = n // d

            cand1 = s[:d]
            if works(s, n, d, cand1):
                answer = d
                break

            if block_cnt > 1:
                cand2 = s[d:2 * d]
                if works(s, n, d, cand2):
                    answer = d
                    break

        print(answer)

solve()
```辅助函数`works`检查候选期间是否可以生成与以下内容不同的字符串`s`至多处于一个位置。 它不是显式构建重复的字符串，而是比较字符`s[i]`和`pat[i % d]`。 这避免了额外的内存并保持检查线性。 

除数生成使用标准平方根枚举。 将每个除数对相加，然后对列表进行排序，以便从最小到最大测试周期。 

对于每个除数，算法仅检查前两个块。 这是关键的优化。 正确性论证表明，如果存在有效周期，则这两个块之一必须等于真实周期。 

里面提前退出`works`很重要。 一旦出现多个不匹配，该候选就永远不会有效，因此没有理由继续扫描该字符串。 

## 工作示例

 ### 示例 1

 输入：```
4
abaa
```候选除数是`1, 2, 4`。 

| d | 候选人 | 不匹配 | 有效 |
 | --- | --- | --- | --- |
 | 1 | 一个 | 1 | 是的 |

 重复的字符串是`"aaaa"`。 它不同于`"abaa"`只在位置 2，所以答案是`1`。 

此示例说明了为什么我们必须允许进行一项修改。 该字符串原本不是带有句点的周期性字符串`1`，但固定单个字符后就变成周期性的。 

### 示例 2

 输入：```
8
hshahaha
```除数是`1, 2, 4, 8`。 

| d | 候选人 | 不匹配 | 有效 |
 | --- | --- | --- | --- |
 | 1 | 小时 | 3 | 没有 |
 | 2 | HS | 4 | 没有 |
 | 2 | 哈 | 1 | 是的 |

 第二块`"ha"`是正确的时期。 

重复它给出：```
hahahaha
```它与原始字符串只有一个位置不同。 

此跟踪说明了为什么仅检查第一个块是不够的。 损坏的字符可能位于第一个块内，从而使第二个块成为正确的周期。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n·d(n)) | O(n·d(n)) | 每个除数最多对字符串执行两次完整扫描 |
 | 空间| O(d(n)) | O(d(n)) | 除数列表的存储 |

 对于每个除数，我们最多测试两个候选者，每个测试扫描字符串一次。 任意整数的约数个数，最多`2 · 10^5`很小，因此总工作量保持在限制范围内。 与可用的 256 MB 相比，内存使用量可以忽略不计。

 ## 边缘情况

 考虑：```
1
4
abaa
```对于除数`1`，候选期为`"a"`。 重复它会产生`"aaaa"`。 不匹配计数恰好为一。 算法立即返回`1`。 

这验证了我们是否正确处理了单次修改后变为周期性的字符串。 

考虑：```
1
4
abba
```对于除数`1`，失配数超过 1。 对于除数`2`, 两位候选人`"ab"`和`"ba"`产生多个不匹配。 唯一除数`4`成功了。 

算法返回`4`，表明它不会仅仅因为某些残基类别看起来相似而错误地接受较短的时期。 

考虑：```
1
8
hshahaha
```第一个块是`"hs"`第二个块是`"ha"`。 真实的时期是`"ha"`，但第一个块包含损坏的字符。 仅测试第一个块将会失败。 该算法还测试第二个块，只发现一个不匹配，并正确返回`2`。 

这正是促使检查前两个块的情况。 

考虑：```
1
6
aaabaa
```对于除数`1`, 重复的字符串`"aaaaaa"`恰好有一个位置不同。 该算法计算全局不匹配，而不是计算残基类别之间的分歧，因此答案正确地报告为`1`。 这避免了过多计算单个坏角色的影响。
