 ## 解决方案
 ## 问题理解

 我们获得了多达 50,000 个独立查询。 对于每个查询，都有一个数字`n`提供，其中`1 ≤ n ≤ 100000`。 

如果一个数字通常的十进制表示形式中的每个数字都是以下之一，则该数字称为二进制十进制：`0`或者`1`。 例子包括`1`,`10`,`11`,`101`， 和`1001`。 

任务是确定是否`n`可以写成一个或多个二进制小数的乘积。 重复是允许的，所以像`121 = 11 × 11`是有效的。 

从约束中得到的最重要的观察结果是`n`永远不会超过`100000`。 尽管有很多测试用例，但可能值的范围非常小。 我们可以预处理所有数字，而不是从头开始解决每个查询`100000`一次并在恒定时间内回答每个测试用例。 

一些边缘情况值得关注。 

考虑：```
1
1
```正确答案是`YES`。 数量`1`本身是二进制十进制。 仅尝试将数字分解为较小的二进制小数的解决方案可能会意外地拒绝它。 

考虑：```
1
100000
```正确答案是`YES`，因为每个数字要么是`0`或者`1`，因此数字本身已经是由一个因子组成的有效乘积。 

考虑：```
1
99
```正确答案是`NO`。 虽然`99 = 9 × 11`, 因子`9`不是二进制十进制。 如果不小心实现，仅检查某个除数是否为二进制十进制并递归地忽略其余因子的有效性，则会产生错误的答案。 

另一个微妙的情况是：```
1
121
```答案是`YES`， 虽然`121`本身不是二进制十进制。 它等于`11 × 11`，所以我们必须考虑二进制小数的乘积，而不仅仅是其自身数字为的数字`0`和`1`。 

## 方法

 一个直接的蛮力想法是递归地分解每个数字。 对于给定的`n`，枚举不超过的所有二进制小数`n`，尝试除以每一个，并递归检查商。 

这是正确的，因为每个有效的表示都可以被视为一次重复删除一个二进制十进制因子。 问题是重复。 多达50,000个测试用例，许多数字被反复检查。 递归探索还通过不同的分解顺序重新访问相同的状态。 

关键的观察来自于非常小的极限，`n ≤ 100000`。 

二进制小数最多有多少位`100000`？ 一个六位数字，其数字限制为`{0,1}`最多有`2^6 = 64`的可能性。 排除无效值（例如前导零形式和超过的数字）后`100000`，仅剩几十人。 

这就把问题变成了可达性问题。 

开始于`1`，这当然是有代表性的。 如果一个数字`x`是可表示的，那么`x × b`也可以表示每个二进制十进制`b`，前提是产品不超过`100000`。 

我们可以构建每个可表示的数字，直到`100000`使用简单的动态过程。 预处理完成后，回答查询只是检查是否`n`已达到。 

这本质上是一个图表，其中每个数字都指向`number × binary_decimal`。 由于只有`100000`状态和只有几十个二进制十进制乘法器，整个可达集可以计算一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 因式分解深度呈指数 | O(深度) | 太慢了 |
 | 最佳 | O(MAX × B) 预处理，每次查询 O(1) | O(最大) | 已接受 |

 这里`MAX = 100000`和`B`是二进制小数的位数`100000`，只有几十个。 

## 算法演练

 1. 生成每个二进制小数不超过`100000`。 

如果一个数字是二进制十进制，如果每个十进制数字是`0`或者`1`。 由于限制很小，我们可以简单地测试以下每个数字`1`到`100000`。 
2. 创建布尔数组`reachable`尺寸的`100001`。`reachable[x]`将意味着`x`可以表示为二进制小数的乘积。 
3. 马克`reachable[1] = True`。 

数量`1`本身是二进制十进制，因此它是有效的起始状态。 
4. 迭代所有数字`1`到`100000`。 

每当`reachable[x]`是真的，治疗`x`作为已知有效的产品。 
5. 对于每个二进制小数`b`, 计算`x × b`。 

如果产品不超过`100000`，将其标记为可达。 

这反映了问题的定义。 将一个有效乘积乘以另一个二进制小数会产生另一个有效乘积。 
6. 预处理后，通过打印回答每个测试用例`YES`如果`reachable[n]`是真的并且`NO`否则。 

### 为什么它有效

 证明直接由乘法闭包得出。 

最初，`reachable[1]`是真的。 每次该算法标记一个新数字时，都会通过将已经可表示的数字乘以二进制小数来实现。 因此，每个标记的数字都是真正可代表的。 

对于另一个方向，假设有一个数字`n`可以写成二进制小数的乘积：```
n = b1 × b2 × ... × bk
```开始于`1`，预处理可以乘以`b1`，然后由`b2`， 等等。 每个中间产品都被标记为可达，所以最终`n`也被标记。 

该算法生成的集合正是可表示为二进制小数乘积的数字集合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXN = 100000

def is_binary_decimal(x):
    while x:
        d = x % 10
        if d != 0 and d != 1:
            return False
        x //= 10
    return True

binary_decimals = []
for x in range(1, MAXN + 1):
    if is_binary_decimal(x):
        binary_decimals.append(x)

reachable = [False] * (MAXN + 1)
reachable[1] = True

for x in range(1, MAXN + 1):
    if not reachable[x]:
        continue

    for b in binary_decimals:
        y = x * b
        if y > MAXN:
            break
        reachable[y] = True

t = int(input())
ans = []

for _ in range(t):
    n = int(input())
    ans.append("YES" if reachable[n] else "NO")

sys.stdout.write("\n".join(ans))
```第一部分生成所有二进制小数，最多`100000`。 由于限制很小，因此逐位检查每个数字是完全可以负担​​的。 

这`reachable`数组存储预处理结果。 我们从`1`并重复乘以每个二进制小数。 由于数字是按递增顺序处理的，因此每个可达值最终都会将其可达性传播到更大的产品。 

一个有用的实现细节是`break`在乘法循环内。 二进制小数列表已排序。 一次`x * b`超过`100000`，以后的每个乘数也会超出限制，因此继续下去将是浪费精力。 

无需特殊处理`1`。 由于它既是起始状态又是二进制十进制，预处理自然会处理它。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(最大 × B + t) | 预处理访问每个可达状态并尝试所有二进制十进制乘法器 |
 | 空间| O(最大) | 可达性数组为每个数字存储一个布尔值 |

 和`MAX = 100000`而且只有几十个二进制小数，预处理很容易足够快。 每个查询都会在恒定时间内得到答复，这对于多达 50,000 个测试用例来说是理想的选择。

 ## 边缘情况

 考虑输入：```
1
1
```预处理开始于`reachable[1] = True`。 自从`1`已经可表示，查询立即返回`YES`。 这可以正确处理尽可能小的输入。 

考虑：```
1
100000
```该数字本身是二进制十进制，因为它的数字只是`1`和`0`。 在预处理过程中，乘以`1`经过`100000`标记`reachable[100000] = True`。 答案是`YES`。 

考虑：```
1
121
```该算法首先标记`11`可从 到达`1`，然后标记`121 = 11 × 11`。 该数字不是二进制十进制，但属于二进制十进制乘法闭包，因此输出为`YES`。 

考虑：```
1
99
```二进制十进制乘法不会产生序列`99`。 由于它从未在可达性表中标记，因此查询返回`NO`。 这避免了仅仅因为数字有一个二进制十进制除数就接受数字的常见错误。
