 ## 解决方案
 ## 问题理解

 我们给出了一系列查询，每个查询都是一个大的正整数，表示电子表格系统中的列索引，该系统使用字母而不是数字来标记列。 标签从单个字母开始，然后是两个字母的字符串，然后是三个字母的字符串，依此类推，遵循大写英文字母的字典模式。 

任务是在该方案下将每个整数位置转换为其对应的“列名”字符串。 关键的困难在于，这不是标准的 26 进制转换，因为没有零数字，并且映射发生了移位，使得 A 对应于 1 而不是 0。 

输入规模很大，最多有 100,000 个查询，每个数字高达 10^18。 这立即排除了任何通过枚举所有先前标签或模拟整个序列来构建字符串的方法。 任何解决方案都必须以相对于值的对数时间处理每个查询，因为线性或基于枚举的方法太慢了。 

26 的幂周围会出现微妙的边缘情况。例如，26 映射到 Z，但 27 映射到 AA，而不是 BA 或类似的东西。 另一个棘手的情况是像 52、53 和 702 这样的值，如果我们没有正确处理缺少零的情况，朴素的模 26 逻辑可能会出现错误。 例如，26 应该产生 Z，而朴素的模算术通常会产生空余数或不正确的进位行为，除非进行调整。 

## 方法

 一个暴力的想法是从 1 开始，按顺序重复生成列名，直到到达目标索引。 这在概念上很简单，因为映射是单调的并且按字典顺序排列，因此我们只需增加一个计数器并将每个数字转换为其字符串表示形式，直到达到查询值。 但是，这需要每个查询生成最多 a_i 字符串。 由于 a_i 可以大到 10^18，所以这是完全不可行的，即使对于单个查询也是如此。 

关键的观察结果是，该结构的行为类似于 26 进制数字系统，只不过数字是从 1 到 26，而不是 0 到 25。这意味着我们可以将该数字解释为 1 索引的 26 进制表示形式。 该转换类似于将数字转换为 26 进制，但每当我们提取数字时，我们必须将余数 0 映射到字母 Z 并减少商，然后再继续。 此调整解决了由于缺少零数字而导致的偏移一位的问题。 

我们没有生成所有先前的标签，而是使用重复除以 26 的方式将数字从最低有效位置到最高有效位置直接分解为字符，并在余数变为零时对其进行纠正。

 | 暴力枚举| 每个查询 O(max a_i) | O(1) | O(1) | 太慢了|
 | 位置 Base-26 转换 | 每个查询 O(log a_i) | O(1) 额外（输出除外）| 已接受 |

 ## 算法演练

 我们独立处理每个查询。

1. 从给定的数字a开始。 这表示列标签的无限有序列表中的位置。 
2. 通过取模 26 重复计算标签的最后一个字符。这给出了 0 到 25 范围内的数字，但这里 0 不对应于 A。如果余数为 0，我们将其解释为 26，即字符 Z，并且在继续之前我们还会将数字递减。 
3. 通过将 1 映射到 A、2 映射到 B，以此类推直至 26 映射到 Z，将调整后的余数转换为字符。 
4. 将此字符附加到列表中，因为我们正在从最低有效位置到最高有效位置构建字符串。 
5. 将数字除以 26（整数除法）。 这将我们移至列命名系统中的下一个“数字”。 
6. 重复直到数字变为零。 
7. 将收集到的字符进行反转，得到最终的列标签。 

非显而易见的步骤是当余数为零时的调整。 这有效地改变了表示方式，使每个“数字”都存在于 1 到 26 中，而不是 0 到 25 中，从而保留了该系统中没有零表示的事实。 

### 为什么它有效

 列标签形成以 26 为基数但没有零数字的位置数字系统。 每个有效标签都唯一对应于一系列选择，其中每个位置贡献 1 到 26 之间的值。重复除法过程将这些位置从最不重要到最重要重新构建，并且校正步骤确保使用 Z 表示 26 的倍数等边界情况，而不是错误地溢出到下一个更高的数字。 这保证了整数和字符串之间的双射。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def convert(x: int) -> str:
    res = []
    while x > 0:
        x -= 1
        res.append(chr(ord('A') + (x % 26)))
        x //= 26
    return ''.join(reversed(res))

def main():
    t = int(input())
    for _ in range(t):
        x = int(input())
        print(convert(x))

if __name__ == "__main__":
    main()
```关键的实现选择是在取模之前减一。 这一行解决了由于缺少零数字而引起的偏移一位的问题。 如果没有它，26 的倍数将错误地映射到错误的字母。 

我们以相反的顺序构建结果，因为每个模步骤首先提取最低有效的“数字”。 最后反转可以恢复正确的从左到右的表示。

 ## 边缘情况

 对于输入 26，算法设置 x = 26，然后递减至 25，生成字符 Z，然后终止。 这可以避免产生空余数并确保干净地处理 26 的倍数。 

对于输入 52，第一次迭代在调整后将 52 映射到余数 0，产生 Z，然后继续 x = 1，产生 A。这会产生 AZ，它与预期的字典顺序匹配。 

对于输入 703，重复的除法转换跨越所有三字符边界。 第一步为最后一个位置生成 A，然后类似 AA 的传播生成 AAA。 每个阶段都正确遵循 1 索引数字系统，确认进位传播的行为类似于没有零的位置数字系统。
