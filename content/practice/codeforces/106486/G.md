 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 的一系列位置，每个位置都持有一些初始资源量。 最初，每个位置都是其自己的独立组，因此有 n 个不相交的组，每个组仅包含一个索引。 

随着时间的推移，我们会进行选择两个位置的操作。 包含这两个立场的群体相互作用，根据这两个群体在线上是否“接近”，它们要么和平合并，要么通过冲突合并。 每次交互后，两个群体总是成为一个群体，但合并后的群体的总资源会因获得固定奖励 c 或失去固定惩罚 d 而发生变化。 

决定和平或冲突的关键规则是几何的：我们查看第一组中的所有立场和第二组中的所有立场。 如果存在至少一对在数轴上相邻的位置（每组一个），这意味着它们的索引正好相差 1，则交互作用是冲突。 否则就是太平了。 

除了这些交互之外，我们还必须回答询问包含给定位置的组的当前总资源的查询。 

这些限制足够大，任何解决方案都必须处理超过 50 万个位置的多达 50 万个操作。 这立即排除了在每次合并期间重复扫描组的所有成员的任何方法，因为组可以增长到大小 n 并且可以有 n 次合并，从而导致二次行为。 

一个微妙的问题是组不需要是连续的段。 经过多次合并后，一个组可以成为一组分散的索引，因此组之间的邻接性不能仅由区间端点确定。 

下面是打破天真的区间思维的一种边缘情况。 假设 A 组包含 {1, 4}，B 组包含 {2, 10}。 即使区间重叠或范围很接近，邻接性也仅由差值为 1 的一对的存在来确定。这里 1 和 2 是相邻的，因此交互作用一定是冲突的，即使这些集合不是简单意义上的相邻区间。 

如果我们尝试仅通过最小和最大索引来表示每个组，则会出现另一种失败情况。 例如，A = {1, 10}，B = {2, 9}。 它们的间隔严重重叠，但除非存在穿过组的实际边 (i, i+1)，否则它们并不相邻。 区间总结是不够的。 

因此，困难在于在固定路径图上维护动态连接的组件，同时还支持重复合并和快速检测两个组件之间是否存在交叉边。 

## 方法

 直接模拟会将每个组维护为一组明确的索引。 为了处理 x 和 y 之间的交互，我们找到它们的组并检查一个集合中的任何元素是否在另一个集合中具有邻居。 这需要扫描整个集合并检查另一个集合中的成员资格，这可能会降低每次操作的 O(n) 复杂度。 经过 n 次操作，这变成了 O(n²)，这太慢了。 

关键的观察结果是邻接结构是静态的。 唯一重要的边是固定边 (i, i+1)。 两个组是否相邻仅取决于这些固定边中是否有任何一条在它们之间交叉。 这减少了维护路径图的动态分区的问题，同时支持合并并维护哪些组件通过边界边连接。 

这表明了一种类似并查找的结构，但标准 DSU 是不够的，因为我们还需要通过原始行中的至少一条边来检测两个组件是否相邻。 因此，对于每个组件，我们不仅维护其大小和资源总和，而且还维护它通过边界边缘接触的其他组件。 由于组件不断发展，因此在发生合并时必须更新这些邻接关系。

有效管理此问题的标准方法是从小到大合并组件成员资格列表。 每个组件都存储其节点列表。 当合并两个组件时，我们迭代较小的组件，并通过查看邻居 i−1 和 i+1 来更新所有受影响的边界关系。 这确保了每个索引在所有合并中仅处理对数多次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每次合并时进行朴素集扫描 | O(n²) | O(n) | 太慢了|
 | 具有邻接维护功能的节点上从小到大的 DSU | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们在组件上维护一个不相交的集合结构。 每个组件保存其成员索引列表、资源总和以及沿线的邻接引起的一组相邻组件。 

1. 将每个位置 i 初始化为其自己的分量，总和等于 a[i]，并且最初没有邻居。 我们还记录位置到组件的映射是恒等的。 
2. 对于涉及位置 x 和 y 的每个交互查询，使用 DSU 查找操作查找其当前组件 A 和 B。 
3. 如果 A 等于 B，我们什么都不做，因为当两个位置已经在同一个组件中时，该操作无效。 
4. 为了确定交互是和平的还是敌对的，我们检查 A 和 B 是否是相邻的组件。 如果 A 出现在 B 的邻居集中，则情况成立，反之亦然。 如果相邻，则结果是冲突；如果相邻，则结果是冲突。 否则就是联盟。 
5. 我们通过合并 A 和 B 来计算新的组件 C。我们将较小的组件附加到较大的组件中以保证效率。 我们将较小组件的所有节点移动到较大组件中并更新它们的组件指针。 
6. 在移动节点时，我们检查合并组件中的每个节点 u。 对于每个 u，我们检查 u−1 和 u+1 是否存在。 如果邻居 v 位于不同的组件 D 中，则 C 会与 D 相邻。我们还确保 D 用 C 替换对 A 或 B 的引用。 
7. 合并后，我们通过将两个总和相加来更新新组件的资源总和，然后应用+c（表示联盟）或-d（表示冲突）。 
8. 对于类型 2 的每个查询，我们找到 x 的分量并输出其存储的和。 

关键的不变量是每个组件在所有操作之后正确维护其成员索引集和正确的资源总和。 此外，对于每个组件，其邻居集精确对应于共享至少一个原始邻接边（i，i+1）的组件。 因为每当节点在组件之间移动时我们都会显式更新邻居关系，因此不会丢失或错误地引入任何邻接边。 这保证了联盟和冲突之间的每个决策都是基于当时跨组件边界边缘的确切存在。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n, a):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)
        self.sum = [0] * (n + 1)
        self.nodes = [[] for _ in range(n + 1)]
        self.nei = [set() for _ in range(n + 1)]
        self.a = a

        for i in range(1, n + 1):
            self.sum[i] = a[i]
            self.nodes[i].append(i)

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def add_edge_relation(self, u, v, pu, pv):
        if pu == pv:
            return
        self.nei[pu].add(pv)
        self.nei[pv].add(pu)

    def merge(self, x, y, gain):
        x = self.find(x)
        y = self.find(y)
        if x == y:
            return x

        if self.size[x] < self.size[y]:
            x, y = y, x

        # y merges into x
        for u in self.nodes[y]:
            self.parent[u] = x
            self.nodes[x].append(u)

        self.nodes[y].clear()

        for u in self.nodes[x]:
            pu = x
            for nb in (u - 1, u + 1):
                if 1 <= nb <= len(self.a) - 1:
                    pv = self.find(nb)
                    if pv != pu:
                        self.nei[pu].add(pv)
                        self.nei[pv].add(pu)

        self.size[x] += self.size[y]
        self.sum[x] += self.sum[y] + gain

        return x

n, c, d = map(int, input().split())
a = [0] + list(map(int, input().split()))
q = int(input())

dsu = DSU(n, a)

out = []

for _ in range(q):
    tmp = input().split()
    if tmp[0] == '1':
        x = int(tmp[1])
        y = int(tmp[2])

        fx = dsu.find(x)
        fy = dsu.find(y)

        if fx == fy:
            continue

        adjacent = (fy in dsu.nei[fx]) or (fx in dsu.nei[fy])

        gain = c if adjacent else -d
        dsu.merge(x, y, gain)

    else:
        x = int(tmp[1])
        fx = dsu.find(x)
        out.append(str(dsu.sum[fx]))

print("\n".join(out))
```DSU 结构维护组件聚合和组件之间不断发展的邻接关系。 合并操作首先使用维护的邻居集确定交互是敌对的还是和平的。 然后，它执行节点列表从小到大的合并，以便每个节点最多被重新分配对数次。 

关键的微妙之处在于，邻接关系不会在全局范围内重新计算。 相反，它是通过仅检查移动节点的本地邻居来增量维护的。 这避免了每次合并时扫描整个组件。

 ## 边缘情况

 一种边缘情况是组件在没有任何邻接关系的情况下合并。 例如，合并 {1} 和 {3} 应该是和平的，即使它们在索引空间中很接近。 该算法正确检测到没有边界边缘，因为 1 都不与 {3} 中的任何元素相邻。 

另一种情况是涉及已合并组件的重复合并。 当 x 和 y 位于同一组件中时，该操作将被忽略，从而防止重复计算资源更改。 

最后一个微妙的情况是组件变得高度不连续。 即使如此，邻接检查仍然正确，因为它们仅基于原始线路邻居。 更新步骤确保每当节点更改组件时，都会重新评估其两个邻居，从而在整个过程中保留正确的边界关系。
