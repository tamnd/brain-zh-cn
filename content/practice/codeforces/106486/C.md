 ## 解决方案
 ## 问题理解

 我们正在研究一种游戏机制，其中致命一击的概率不是固定的，而是取决于自上次致命一击以来已经过去了多长时间。 没有暴击的时间越长，发生暴击的几率就越高，上限为 1。 

更准确地说，有一个参数 c 控制这个概率增长的速度。 在任何攻击中，将 i 定义为自上次暴击以来的攻击次数，或者如果尚未发生暴击则自游戏开始以来的攻击次数。 这次攻击是致命一击的概率是 min(1, i · c)。 

在无限的攻击序列中，该系统会产生长期平均临界率。 也就是说，如果我们查看前 n 次攻击中预期的致命一击数量并除以 n，则随着 n 变大，该比率会收敛到某个值 p。 我们给定 p，必须恢复相应的 c。 

关键的困难在于这个过程并不是无记忆的。 每次攻击都取决于之前的“连续失败”持续了多长时间，因此系统是一个更新过程，而不是简单的伯努利序列。 

输入量很小，最多有 100 个测试用例，因此每个测试用例都可以承受对数甚至小型常数因子迭代方法。 重要的是 p 和 c 之间数学关系的正确性，而不是对大型数据结构的优化。 

当 p 极其接近 1 时，会出现微妙的边缘情况。在这种情况下，c 也必须接近 1，并且在求解逆关系时数值稳定性很重要。 另一个边缘情况是 p 非常小时。 那么 c 就很小，系统几乎总是在 i = 1 或 2 时重置，使得期望由概率函数的第一个线性段主导。 

简单的模拟方法会尝试模拟长序列上的马尔可夫过程。 尽管每个步骤都是 O(1)，但收敛到稳态速率的速度非常慢并且取决于方差，这使得它对于像 1e-8 这样严格的误差要求来说不切实际并且在数值上不稳定。 

## 方法

 核心观察是，该过程可以分解为连续关键命中之间的独立“循环”。 每个循环在一次暴击后立即开始，并在下一次暴击时结束。 一个周期的长度决定了长期的暴击率：如果预期的周期长度是E[L]，那么每次攻击的预期暴击次数就是1/E[L]。 

在一个周期内，成功的概率线性增加：在暴击后的第 i 次尝试中，成功概率为 min(1, i c)。 这会根据 i c 是否达到 1 创建两种状态。 令 k 为满足 k c ≥ 1 的最小整数。那么，对于 i < k，概率为 i c，并且在 i = k 时，循环保证结束。 

强力计算将通过对所有可能的失败-成功路径求和来显式计算预期的周期长度。 这很快就会变成 k 的指数，因为每个状态都会根据成功或失败进行分支，但由于 k 可以大到 1/c，因此当 c 很小时，这变得不可行。 

关键的见解是我们不需要直接模拟随机性。 我们只需要期望过程的停止时间，其中每个位置的故障概率是确定的。 这允许我们通过求和生存概率来编写 E[L] 的封闭式表达式作为 c 的函数。 

一旦我们有了 E[L](c)，目标条件就变为 p = 1 / E[L](c)。 由于 E[L](c) 在 c 中是单调的，因此我们可以使用二分查找来求解 c。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(大，不收敛) | O(1) | O(1) | 太慢了|
 | 期望+二分查找| O(log(1/ε) · k) | O(log(1/ε) · k) | O(1) | O(1) | 已接受 |

 ## 算法演练

我们计算固定 c 的预期循环长度，然后使用二分搜索反转关系。 

1. 固定c的候选值。 确定 k = ceil(1 / c)。 这是概率达到 1 的第一个索引。这将过程分为线性增长阶段和确定性终止阶段。 
2. 计算生存概率 S_i，即在尝试 i（包括尝试 i）之前未发生暴击的概率。 最初 S_0 = 1。当 i ≥ 1 时，S_i = S_{i-1} · (1 − min(1, i c))。 这跟踪循环继续经过步骤 i 的可能性。 
3. 预期周期长度是每次试验前所有步骤生存概率的总和。 具体而言，对于所有 i，E[L] = Σ S_{i-1}，因为如果进程尚未终止，则每个步骤贡献 1 个时间单位。 
4. 将 i 从 1 迭代到 k。 对于 i < k，使用 (1 − i c) 乘法更新生存。 当 i = k 时，进程终止，因此我们停止。 
5. 计算 p_hat = 1 / E[L]。 这是该 c 值的长期预期临界率。 
6. 在区间 (0, 1] 内对 c 使用二分查找。对于每个中点，计算 p_hat 并将其与目标 p 进行比较。如果 p_hat 太大，则 c 太大，必须减小；否则增大 c。
 7. 继续，直到间隔小于固定精度阈值（通常为 1e-12），以保证最终绝对误差在 1e-8 以内。 

### 为什么它有效

 该过程是一个更新过程，其中每个周期都是独立且同分布的。 这种系统中事件的长期频率是预期到达间隔时间的倒数。 由于每个周期长度仅取决于 c 而不是历史，因此 E[L](c) 完全表征了系统。 单调性之所以成立，是因为增加 c 会严格增加提前终止的概率，从而减少预期循环长度并增加 p。 这保证了二分搜索收敛到唯一的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def expected_cycle(c):
    s = 1.0
    total = 0.0
    i = 1
    while True:
        prob = i * c
        if prob >= 1.0:
            total += s
            break
        total += s
        s *= (1.0 - prob)
        i += 1
    return total

def solve_case(p):
    lo, hi = 0.0, 1.0
    for _ in range(80):
        mid = (lo + hi) / 2.0
        e = expected_cycle(mid)
        p_hat = 1.0 / e
        if p_hat > p:
            hi = mid
        else:
            lo = mid
    return (lo + hi) / 2.0

t = int(input())
for _ in range(t):
    p = float(input())
    ans = solve_case(p)
    print(f"{ans:.15f}")
```功能`expected_cycle`直接落实更新理念。 它在一个循环中进行连续的尝试，跟踪生存概率和累积期望。 当概率达到 1 时，循环必须结束，因此我们停止累加。 

对 c 进行二分查找是因为将 c 映射到 p 的函数是单调递增的。 循环计数 80 足以使双精度实现远低于 1e-8 的误差。 

一个微妙的点是我们通过生存概率累积预期长度`s`。 这避免了枚举所有故障序列并将指数分支压缩为单个线性遍。

 ## 边缘情况

 当p恰好为1时，唯一一致的配置是c = 1。在这种情况下，第一次之后的每次攻击都保证立即暴击，并且周期长度恰好为1。 

当p极小时，c也很小，生存积衰减得很慢。 预期循环内的循环必须处理多次迭代，但它仍然很快终止，因为当 i c 跨越阈值时概率最终达到 1。 

当 c 接近阈值（其中 i c 在 i 非常大时变为 1）时，浮点精度很重要，因为生存概率的重复相乘可能会下溢。 该算法通过使用双精度并在达到确定性截止时提前停止来避免这种情况。
