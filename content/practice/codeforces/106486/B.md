 ## 解决方案
 ## 问题理解

 我们有一只机器猫沿着从 1 到 1 的直线路径移动$n+1$。 它在时间 0 从位置 1 开始并想要到达位置$n+1$。 每次移动到下一个位置仅消耗一个时间单位。 

能源是关键约束。 猫开始于$E$活力。 在每个单位时间内，其系统仅消耗 1 能量来保持运行。 另外，在该时间单位内，每当它进行一次移动，都会额外消耗1点能量。 因此，停留在原地每单位时间需要消耗 1 能量，前进每单位时间需要消耗 2 能量，同时也会提升其位置。 

在每个中间位置$i$从 1 到$n$，有一个能源站。 车站$i$仅在某个时间间隔内变为活动状态$[l_i, r_i]$，如果猫处于位置$i$在某个整数时间$t$在此间隔内，它可以选择仅激活该站一次以获得$a_i$活力。 每个站最多可以使用一次。 

猫可以向前移动或在当前位置等待。 然而，如果在任何时刻它的能量变为零或负，它就会立即中断并且旅程失败，即使那个时刻恰逢到达车站或最终位置。 

任务是确定到达位置所需的最短时间$n+1$永远不会让能量降至零或更低。 如果不可能，我们必须输出$-1$。 

输入大小足够小，可以对位置进行线性或近线性模拟。 和$n \le 5000$时间窗口可达$10^4$，二次解$n$是边界，但仍然可以接受，而任何涉及位置和时间的完整状态空间的东西都会太大。 

如果我们尝试“贪婪地等待”来匹配车站窗口，就会出现微妙的失败情况。 等待会消耗时间，但也会减少精力，从而使未来的可行性条件变得更加紧张。 一个天真的想法是总是等到车站开放，但这可能会让猫提前耗尽能量。 

另一个微妙的情况是假设收集一个站点总是有助于可行性，而不考虑延迟收集它可能是有害的。 例如，如果一个车站开放较晚，等待它可能会花费比它提供的收益更多的能量。 

## 方法

 蛮力视角是模拟猫随时间移动或等待的所有可能方式，跟踪其位置、时间和能量。 每一步，它都可以前进或停留，只要它在一个站的范围内，它就可能走也可能不走。 这导致了巨大的状态空间$(position, time, energy)$。 即使我们将时间离散化到$10^4$，状态数量变为$n \cdot time \cdot energy$，这远远超出了一秒钟可以处理的范围。 

关键的观察是，一旦我们确定了收集站的顺序和运动时间表，能量就会确定性地演变。 时间总是与位置紧密耦合：每次移动都会使位置增加 1，并且正好消耗 1 个时间单位。 等待不会改变位置，但仍会消耗能量。 这使得等待在大多数情况下都严格占主导地位，因为它会减少能量，但不会改善达到未来职位的结构性限制。 

一个有用的简化是注意到达位置$i$在某个时间$t$无需等待即可给出$t = i - 1$。 任何等待都会增加$t$，但能量会减少完全相同的量，这使得未来的生存更加困难。 因此，任何等待策略只会损害可行性，除非它能够收集否则无法到达的站点，并且甚至已经通过检查该站点在到达时是否可用来考虑该增益。 

因此，我们可以将问题简化为沿路径的直线模拟，始终立即向前移动，并收集在到达时处于活动状态的任何站点。 唯一剩下的问题是，在这种确定性行走过程中，能量是否会降至零或更低。

 ## 算法演练

 我们处理从 1 到$n$同时保持当前的时间和精力。 

1.初始化时间$t = 0$和能量$E_{cur} = E$。 我们还维护收集的站能量的运行总和。 
2. 对于每个位置$i$从 1 到$n$，我们立即转向它。 这意味着时间变成$t = i - 1$。 
3.就位$i$，检查该时刻是否处于活动状态$t$， 意义$l_i \le t \le r_i$。 如果它是活跃的，我们收集它的能量一次并添加$a_i$到$E_{cur}$。 
4.在可能的收集之后，我们检查猫此时是否还活着。 截至时间消耗的能量$t$包括$t$从时间消耗和其他$i-1$来自移动成本，因此生存条件变为$E_{cur} > 2t$。 如果失败，我们终止并返回$-1$。 
5. 如果所有位置都处理成功，猫就到达位置$n+1$在某个时间$n$，所以我们输出$n$。 

忽略等待背后的原因是，任何延迟都会同等地增加时间和能量消耗，但不会改善时间和位置之间的结构关系。 由于生存取决于线性组合$E_{cur} - (time + moves)$，不必要地增加时间会严格降低可行性。 

### 为什么它有效

 在位置$i$，最早可能到达时间固定为$i-1$，任何偏差只会增加时间，同时减少能量。 由于可行性条件单调依赖于时间，因此延迟永远无法将不可能的状态转变为可能的状态，除非它能够实现站点收集，但站点收集本身仅取决于到达时是否处于固定间隔内。 因此，在最早到达时间检查站点激活足以捕获所有有益的集合，并且任何等待策略都以立即移动为主。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, E = map(int, input().split())
    stations = []
    for _ in range(n):
        a, l, r = map(int, input().split())
        stations.append((a, l, r))

    cur_energy = E

    for i in range(1, n + 1):
        t = i - 1

        a, l, r = stations[i - 1]
        if l <= t <= r:
            cur_energy += a

        if cur_energy <= 2 * t:
            print(-1)
            return

    print(n)

if __name__ == "__main__":
    solve()
```该代码直接模拟唯一相关的时间线：每个位置一步。 时间变量隐含为$i-1$。 在每一步中，我们首先检查该站在当前到达时间是否可以使用，然后更新能量，最后验证生存。 

一个常见的陷阱是颠倒检查和收集的顺序。 “能量变为零立即导致失败”的条件意味着检查必须在收集之后但在继续之前进行。

 ## 边缘情况

 一种重要的边缘情况是车站恰好在到达时间打开$t = i-1$。 在这种情况下，必须在检查生存之前对站点进行计数，因为能量立即受到该时间步的站点收集的影响。 该算法通过检查来正确处理这个问题$l_i \le t \le r_i$在生存条件之前。 

另一种情况是当能量恰好等于$2t$。 由于规则是能量必须严格保持为正，所以平等就是失败。 该代码强制执行此操作`cur_energy <= 2 * t`导致立即终止。 

最后一个边缘情况是一个站有非常大的$a_i$出现较早，但超出了可到达的时间范围。 即使它很大，也不能使用它，除非它的间隔包含确定性的到达时间，这可以防止任何错误的过度计数。
