 ## 解决方案
 ## 问题理解

 我们得到一个块的集合，每个块都有一个正整数大小。 我们想将它们全部堆叠成一个垂直的塔。 唯一的规则是，只有当一个块的大小严格小于其下面的块时，才可以将其放置在另一个块的顶部。 每个块必须只能使用一次，并且所有块必须属于同一塔。 

任务是决定是否可以形成这样的单塔。 

输入大小可以大到200000个块，每个大小可以大到10^9。 这立即排除了任何尝试模拟所有可能的堆叠顺序或回溯排列的解决方案。 任何二次或指数的东西都是遥不可及的。 解决方案必须本质上是线性的或线性的，很可能是 O(n log n)。 

一个微妙的一点是平等是被禁止的。 如果两个块具有相同的大小，则它们不能在任一方向上堆叠在一起。 这就产生了一个硬约束：相等的值就像相同的“高度”一样，相互阻挡。 

经常打破天真的推理的一种边缘情况是所有值都相等。 例如，输入`1 1`显然无法形成一座塔，因为两者都不能叠在另一个之上。 另一个重要的边缘情况是单元素数组，例如`5`，这始终有效。 

## 方法

 强力解释是尝试通过选择任何块作为底部，然后重复选择任何未使用的较小块放置在顶部来构建有效的排序。 这本质上是在每个步骤中通过约束检查来探索排列。 

这在概念上是有效的，因为它直接强制执行严格的递减条件。 然而，在每一层都可能有许多候选选择，并且搜索空间的大小会变成阶乘。 当n达到200000时，这是完全不可行的。 

关键的观察结果是，问题实际上并不取决于排序之外的邻接选择。 由于每个块必须以严格递减序列出现，因此我们提出一个更简单的问题：我们可以使用所有元素一次将所有元素排列成严格递减序列吗？ 

只有当且仅当所有值都不同时，这才是可能的。 如果两个元素相等，则无法在不违反规则的情况下对它们进行严格递减排序，因为相等破坏了严格性，我们无法用相同大小的中间值“分离”它们。 

因此，整个问题归结为检查是否存在重复项。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了|
 | 排序/哈希检查重复项 | O(n log n) 或 O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取代表块大小的所有数字。 
2. 检测是否有任何值出现多次。 
3. 如果存在重复项，请立即断定严格的堆叠顺序是不可能的。 
4. 否则，得出结论：所有元素都可以严格按降序排列，因此存在有效的塔。 

步骤 3 背后的原因是，任何重复对都会强制违反最终堆栈中某个位置的严格不平等，无论顺序如何。 

## 为什么它有效

 有效的塔完全对应于严格降序排列的所有元素的排列。 严格递减序列要求每个相邻对都满足`a[i] > a[i+1]`。 如果两个值相等，它们必须出现在序列中的某个位置，但无论它们放在哪里，它们要么变得相邻，要么被较小的值分开。 在这两种情况下，其中一个将无法在完整排列中保持相对于其邻居的严格排序。 因此，任何重复项的存在都会使任务变得不可能，而没有重复项则保证按降序排序会产生有效的塔。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())
a = list(map(int, input().split()))

seen = set()
for x in a:
    if x in seen:
        print("No")
        sys.exit(0)
    seen.add(x)

print("Yes")
```该实现直接跟踪我们之前是否见过一个值。 一旦发现重复，我们就可以提前终止，因为有效的塔是不可能的。 如果循环结束，所有值都是不同的，并且通过排序存在严格递减的排序，即使我们没有显式构造它。 

关键的设计选择是提前退出，这可以避免在最坏的情况下进行不必要的工作。 使用集合可确保平均 O(1) 成员资格检查，使解决方案保持线性期望。

 ## 边缘情况

 单个元素的情况如`7`由于不需要比较，因此立即通过，并且该集合保持为空，直到插入完成。 算法正确输出 Yes。 

完全相等的数组，例如`5 5 5 5`第二次插入失败，因为第二个元素已经在集合中。 检测是立即的，因此不会进行进一步的处理。 

混合情况，例如`2 1 2`也正确失败。 插入后`2`和`1`，最后的`2`即使重复项不相邻，也会触发重复检查，确认相邻性无关紧要，只有全局唯一性才重要。
