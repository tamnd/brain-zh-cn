 ## 解决方案
 ## 问题理解

 给定一个长序列，其长度为$N^2$，以及来自的每个值$1$到$N$准确地出现$N$次。 该序列旨在解释为涉及的行动的时间表$N$以循环结构排列的标记令牌。 值的每次出现都描述了与该令牌相关的移动或交互。 

核心问题是这个序列是否可以在隐藏的结构规则下以一致的方式实现：动作必须可分解为$N$循环子序列，每个序列的行为就像标签的“轮换时间表”。 换句话说，我们试图决定序列是否可以分为$N$有效链，每条链循环通过$1 \to 2 \to \dots \to N \to 1$按顺序排列，尊重外观限制。 

约束足够大，任何显式搜索分解或模拟元素到链的所有分配的尝试都会发生组合爆炸。 一个天真的分配过程将有效地分支每个出现属于哪个子序列，从而导致指数可能性$N^2$。 这立即排除了回溯或强力分区。 

当满足局部频率条件但全局结构不可能时，就会出现微妙的故障情况。 例如，可以构造前缀，其中值$y$与以下相比出现得太早$y-1$，造成了太多“无关联”事件发生的情况$y$存在。 贪婪的分配可能仍然在本地成功，但后来变得不可能扩展，因为子序列用完了有效的前驱。 

关键的困难在于，可行性不在于总计数，而在于相邻值的出现如何在所有前缀之间交错。 

## 方法

 直接方法将尝试显式地将分解构造为$N$循环子序列。 我们扫描数组并将每个元素分配给可以合法接受它的子序列之一，这意味着它具有已放置的循环中的前一个值。 这就像一个约束调度问题$N$资源和$N^2$事件。 

虽然这种贪婪构造在概念上是正确的，但维护所有可能的子序列并在每一步检查有效位置会导致昂贵的状态爆炸。 在最坏的情况下，每个元素都需要扫描许多子序列，并级联更新，复杂度约为$O(N^3)$或者更糟，具体取决于实施情况。 

结构洞察力是，连续值之间的前缀不平衡完全捕获了可行性。 对于每个前缀和每个值$y$，出现的次数$y$到目前为止看到的次数不能超过出现的次数$y-1$到目前为止已经不止一个看到过。 这个条件是充分必要的，因为每一条“链”最多只能贡献一个无与伦比的$y$任何时候，以及每一个额外的$y$必须有前面的支持$y-1$在某个链条中。 

这将整个问题简化为维护前缀计数并检查所有值的简单不等式。

 ## 算法演练

 我们将问题转换为序列上的前缀计数条件。 

### 步骤

 1.初始化频数表`cnt[y]`为了价值观$1 \ldots N$，一切从零开始。 这会跟踪到目前为止每个值在前缀中出现的次数。 
2. 从左到右扫描序列。 对于每个位置$i$, 增量`cnt[x[i]]`。 这可以在每一步保持正确的前缀频率。 
3. 更新位置后$i$，检查所有值的条件$y \ge 2$：

确保`cnt[y] <= cnt[y-1] + 1`。 

这强制执行该值$y$从未“超越”其前身$y-1$由不止一次发生。 
4. 如果发现任何违规，立即断定该序列无效。 
5. 如果扫描完成且没有违规，则序列有效。 

### 为什么它有效

 键不变量是在任何前缀处，每个值$y$最多只能有一个“不匹配”的出现，尚未得到相应的支持$y-1$。 每个有效链都会贡献一个待处理的槽位，用于从$y-1$到$y$。 如果$y$超过$y-1$由不止一个，某些事件的发生$y$不能在不破坏顺序的情况下放入任何链中，从而使分解变得不可能。 相反，如果不等式始终成立，我们总是可以将每次出现的$y$扩展现有链条或启动单个允许的新的不匹配的链条位置，从而保证可施工性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))

    cnt = [0] * (n + 1)

    for v in a:
        cnt[v] += 1

        for y in range(2, n + 1):
            if cnt[y] > cnt[y - 1] + 1:
                print("No")
                return

    print("Yes")

if __name__ == "__main__":
    solve()
```该实现维护前缀计数并在每次更新后立即检查邻接约束。 内循环结束$y$就足够了，因为只有相邻的差异才重要； 任何值的违规都会在出现时在本地检测到。 

一个微妙的细节是检查必须在每次增量之后进行，而不是在完整扫描之后进行，因为该属性是依赖于前缀的。 延迟验证可能会错过中间无效状态，这些状态稍后会被未来发生的情况“掩盖”。

 ## 边缘情况

 一种重要的边缘情况是，在其前任标签出现足够多的情况之前，更高的标签出现得太早。 例如，输入：```
3
1 3 3 ...
```立即失败，因为 3 出现了第二次，而 2 尚未建立足够的数量。 该算法在精确的前缀处检测到这一点，其中`cnt[3] > cnt[2] + 1`，防止接受任何无效的完成。 

另一种情况是值完全平衡但发生了变化，例如从重复出现最高标签开始。 即使总计数在最后匹配，前缀检查也会提前失败，这是正确处理的，因为算法永远不会延迟对最终状态的验证。
