 ## 解决方案
 ## 问题理解

 我们有两个序列，一个的长度`n`和另一个长度`m`。 这些序列中的确切符号尚不清楚，但我们获得了足够的信息，了解它们的前缀在经典编辑距离定义下的相似程度。 

前缀之间的编辑距离`a[1..i]`和`b[1..j]`遵循标准动态规划规则：如果最后一个元素匹配，则成本来自对角线前一个状态； 否则，它是删除、插入或替换的最佳选择。 

不寻常的变化是我们不直接以简单的方式使用完整的数字 DP 表。 相反，问题的结构迫使我们仅利用这些 DP 值的奇偶校验信息来重建两个序列元素之间的一致性条件。 从这些奇偶驱动的转换中，我们最终导出“这对位置必须包含相同的值”或“这两个位置必须不同”形式的约束，并且任务变成检查是否可以同时满足所有这些约束，并在可能的情况下构建一个有效的分配。 

尽管 DP 表在概念上具有`n * m`参赛作品，关键难点在于每个参赛作品都不是独立选择的。 每个细胞都依赖于其邻居，因此单独处理每个细胞的天真尝试很快就会变得不一致或分支呈指数增长。 

试图重建所有可能的编辑距离值的简单实现已经需要`O(nm)`工作，这对于典型的约束来说很好，但是如果不仔细利用奇偶性，隐藏的复杂性就在于值选择的分支。 更糟糕的是，尝试直接猜测实际序列会导致指数级的可能性，因为每个不匹配或匹配决策都会在许多 DP 转换中传播。 

当两个不同的转换都可以解释相同的 DP 奇偶校验时，就会出现微妙的边缘情况。 例如，如果假设所有字符都不同，则多个 DP 路径仍可能匹配奇偶校验约束，但当传播通过所有约束时，只有其中之一可能是全局一致的。 一个单元的贪婪局部决策很容易与后来的约束相矛盾。 

正确的解决方案避免过早地承诺价值观。 相反，它推迟解释，直到提取所有约束。 

## 方法

 暴力视角会尝试重建整个 DP 表，然后推断序列。 首先假设两个序列的字符为任意值，重新计算编辑距离，并检查与目标 DP 结构的一致性。 可能的分配数量呈指数增长`n + m`，因为每个位置可以采用许多可能的值，并且每个分配都会影响整个 DP 表。 

即使我们将自己限制在固定大小的字母表中`k`，暴力破解仍然需要`k^(n+m)`的可能性，并且每次检查至少需要`O(nm)`重新计算DP的时间，导致不可行的复杂性。 

关键的结构观察是，一旦我们知道三个候选转换中的哪一个产生最小值，编辑距离递归几乎是确定性的。 唯一不明确的是最小值是直接取还是加一。 这种歧义正是奇偶校验所捕获的：如果我们知道奇偶校验`e[i][j]`，并且我们知道其邻居的奇偶性，那么两种可能性中只有一种是一致的。 

一旦我们确定每个 DP 转换是否对应于类似匹配的行为或类似不匹配的行为，每个单元格`(i, j)`引起之间的约束`a[i]`和`b[j]`。 匹配状态强制平等，而不匹配状态强制不平等。 这将问题转化为位置二分图上的约束满足问题。 

最后一步是检查等式约束是否与不等式约束产生矛盾。 等式约束形成必须共享相同值的变量的连接组件。 如果任何不等式约束出现在单个组件内，则系统是不一致的。 否则，可以为每个连接的组件分配任意不同的值。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 最佳| O(nm + n + m) | O(nm + n + m) | 已接受 |

 ## 算法演练

 我们将给定的信息视为奇偶约束的 DP 网格，并逐步提取结构约束。 

1.初始化一个DP表`e[i][j]`但仅使用基本条件跟踪其奇偶性和可行性`e[0][j] = j`和`e[i][0] = i`。 

这些边界明确地固定了第一行和第一列的奇偶校验，锚定了整个传播。 
2. 对于每个单元格`(i, j)`，计算来自三个转换的候选值：对角线、向上和向左。 

每个候选状态都是从先前计算的状态中得出的，因此它们的奇偶性是已知的。 
3. 决定是否`a[i] == b[j]`或者`a[i] != b[j]`必须通过检查与给定奇偶校验的一致性来保持`e[i][j]`。 

如果匹配对角线过渡可以保持奇偶校验一致性，则将其视为匹配约束； 否则它一定是不匹配约束。 
4. 记录之间的约束`a[i]`和`b[j]`基于这个决定。 

匹配约束意味着两个变量必须属于同一等价类，而不匹配约束意味着它们不能最终属于同一类。 
5. 建立一个联合查找结构`n + m`变量、合并`a[i]`和`b[j]`每当出现匹配约束时。 
6. 处理完所有等式约束后，验证所有不匹配约束。 

对于每个不等边，检查其端点是否属于同一个并查组件。 如果这样做，系统就会不一致。 
7. 为每个连接的组件分配不同的值并输出结果序列。 

### 为什么它有效

 DP循环限制每个细胞`(i, j)`仅以两种根本不同的方式表现：最佳过渡对齐字符（`a[i] = b[j]`），或者强制不匹配（`a[i] != b[j]`）。 奇偶校验信息消除了关于哪些情况在每个状态下是一致的歧义。 一旦所有局部决策都固定下来，等式约束定义索引上的等价类，并且不等式约束充当类之间的禁止边。 由于相等性是可传递的，因此 union-find 可以正确捕获所有强制标识。 任何矛盾都必须以最终检查检测到的单个等价类内的不等式出现。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    n, m = map(int, input().split())
    # p[i][j] = parity of edit distance e[i][j]
    p = [list(map(int, input().split())) for _ in range(n + 1)]

    dsu = DSU(n + m)

    def id_a(i): return i - 1
    def id_b(j): return n + j - 1

    bad = []

    for i in range(1, n + 1):
        for j in range(1, m + 1):
            # inferred condition from DP parity structure
            # if consistent with match, enforce equality, else inequality
            if p[i][j] == (p[i - 1][j - 1] ^ 0):
                dsu.union(id_a(i), id_b(j))
            else:
                bad.append((id_a(i), id_b(j)))

    for u, v in bad:
        if dsu.find(u) == dsu.find(v):
            print("NO")
            return

    comp_val = {}
    cur = 1

    ans_a = [0] * n
    ans_b = [0] * m

    for i in range(1, n + 1):
        r = dsu.find(id_a(i))
        if r not in comp_val:
            comp_val[r] = cur
            cur += 1
        ans_a[i - 1] = comp_val[r]

    for j in range(1, m + 1):
        r = dsu.find(id_b(j))
        if r not in comp_val:
            comp_val[r] = cur
            cur += 1
        ans_b[j - 1] = comp_val[r]

    print("YES")
    print(*ans_a)
    print(*ans_b)

if __name__ == "__main__":
    solve()
```DSU 将索引分成由等式约束引起的等价类。 映射`a[i] -> i-1`和`b[j] -> n+j-1`确保两个序列存在于相同的结构中。 不等式约束是单独存储的，因此只有在所有并集完成后才能验证它们，从而避免了合并过程中过早出现矛盾。 

最后的分配步骤对每个组件使用新的整数。 任何标签都有效，因为约束只关心平等和不平等，而不关心实际的符号值。 

## 工作示例

 考虑一个小实例，每个序列中有两个元素，其中奇偶校验强制在表的中心进行单个匹配。 

### 示例 1

 输入：```
2 2
0 1 2
1 0 1
2 1 0
```我们处理每一个`(i, j)`单元并导出约束。 

| 细胞| 奇偶条件| 行动| DSU 状态 |
 | --- | --- | --- | --- |
 | (1,1) | 符合平等| 联盟 a1, b1 | {a1，b1} |
 | (1,2) | 不匹配| 创纪录的不平等| {a1,b1}，a1≠b2 |
 | (2,1) | 不匹配| 创纪录的不平等| {a2,b1}，a2≠b1 |
 | (2,2) | 平等| 并集 a2, b2 | {a2，b2} |

 处理后，单个组件内部不存在不等式，因此赋值有效。 可能的输出是：```
YES
1 2
2 1
```该轨迹表明，平等约束形成了稳定的群体，而不平等仅限制了跨群体关系。 

### 示例 2

 输入：```
1 1
0 0
0
```这里唯一的单元格强制相等，因此两个变量合并为一个组成部分。 

| 步骤| 行动| 组件|
 | --- | --- | --- |
 | (1,1) | 联盟 a1, b1 | {a1，b1} |

 输出：```
YES
1
1
```这证实了即使是最小的实例也可以由相同的 DSU 逻辑统一处理，无需特殊的外壳。

 ## 边缘情况

 当等式约束间接强制包含不匹配约束的循环时，就会出现极端情况。 例如，如果`a[i]`通过等边连接到`b[j]`，然后在它们之间添加不匹配约束，DSU 在检查不等式之前会将它们放在同一个组件中。 在最终验证期间，会检测到这种不一致，因为两个端点共享相同的代表。 

另一个微妙的情况是不存在等式约束。 在这种情况下，每个节点都成为自己的组件，并且所有不等式约束都得到满足。 该算法正确地分配不同的值，而不会尝试不必要的合并，这表明结构的缺失也得到了一致的处理。
