 ## 解决方案
 ## 问题理解

 我们得到了一份清单`2n`正整数，我们需要精确执行`n`移动。 每一步都包括从列表中选择两个数字，将两个数字中较小的添加到我们的分数中，然后从列表中删除这两个数字。 我们的任务是在完成所有动作后使总分最大化。 每个测试用例的输出是一个整数，表示可达到的最高分数。 

限制条件适中：`n`最多可以有 50 个，这意味着列表最多有 100 个元素。 由于数字本身可以大到$10^7$，我们需要注意算术，但 Python 在这里可以轻松处理整数。 时间限制为1秒，最多可以有5000个测试用例。 这意味着每个测试用例必须运行得非常快，最好是相对于元素数量呈线性，当然不是二次方。 

例如，当所有数字都相等时，就会出现微妙的边缘情况`2 2 2 2`。 任何忽略顺序的天真的配对可能会意外地假设不同的结果，但这里的最大分数只是每对中较小元素的总和，这些元素都是相同的。 另一种边缘情况是最大的数字与最小的数字配对。 粗心的贪婪选择，比如总是将两个最大的配对，可能会导致分数不理想。 例如，`[1, 2, 3, 100]`如果我们配对会得到更高的分数`1`和`2`和`3`和`100`而不是`100`和`3`和`2`和`1`。 

## 方法

 暴力方法将尝试所有可能的数字配对，计算每个移动序列的结果分数，并选择最大值。 和`2n`元素，将它们配对的方式数量为$(2n-1) \cdot (2n-3) \cdot ... \cdot 1$，呈超指数增长。 即使是为了`n=10`，这已经是不可能的了。 

关键的观察是，在每一步中，我们只将这对中的最小值添加到分数中。 这意味着为了最大化我们的分数，我们应该确保较小的数字不会因与极大的数字配对而被浪费。 换句话说，如果我们对数组进行排序并将数字连续配对，则在给定剩余数字的情况下，每对中较小的数字尽可能大。 排序确保每一步都贡献尽可能高的值`min(x, y)`在那个阶段。 这将问题简化为对数组进行排序并从最小的数字开始对所有其他数字求和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O((2n)!) | O((2n)!) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，读取整数`n`和名单`2n`数字。 
3. 按非降序对数字列表进行排序。 排序对数字进行组织，以便将小数字配对在一起并充分贡献分数。 
4. 初始化变量`score`为零。 这将累积最小值的总和。 
5. 迭代已排序的列表，添加每隔一个的数字（索引`0, 2, 4, ..., 2n-2`） 到`score`。 这些是每个连续对中较小的元素。 
6. 打印`score`对于每个测试用例。 

为什么有效：排序保证我们形成的每一对都包含两个连续的数字。 在这样的一对中，较小的数字始终是剩余数字中最大可能的选择之一，因此所有这些最小值的总和最大化。 任何其他配对要么会减少一对中的最小值，要么通过将其与更小的数字配对而浪费更大的数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()
    score = sum(a[i] for i in range(0, 2*n, 2))
    print(score)
```该解决方案使用有效地读取输入`sys.stdin.readline`快速处理多个测试用例。 排序至关重要，因为它可以确保最小的数字以最佳方式配对。 求和时在范围内使用 2 的步长可确保我们从每个连续对中准确选择较小的元素。 忘记这个步长会产生不正确的分数。 Python 处理整数不会溢出，因此对于大值不需要特别小心。 

## 工作示例

 输入跟踪`1 2 3 100`和`n=2`:

 | 步骤| 排序数组 | 成对| 分数 |
 | ---| ---| ---| ---|
 | 初始| [1, 2, 3, 100] | - | 0 |
 | 对 1 | [1, 2] | 最小值=1 | 1 |
 | 配对 2 | [3, 100] | 分钟=3 | 4 |

 轨迹显示较小的数字配对以最大化贡献。 配对`100`和`1`只会给`1 + 2 = 3`，这更糟。 

输入跟踪`[1, 1, 1, 1, 1, 1]`和`n=3`:

 | 步骤| 排序数组 | 成对| 分数 |
 | ---| ---| ---| ---|
 | 初始| [1, 1, 1, 1, 1, 1] | - | 0 |
 | 对 1 | [1, 1] | 1 | 1 |
 | 配对 2 | [1, 1] | 1 | 2 |
 | 对 3 | [1, 1] | 1 | 3 |

 这证实了当所有数字都相等时，算法仍然会产生正确的总和。

 ## 边缘情况

 例如，当所有数字都相等时`n=3`和`[2, 2, 2, 2, 2, 2]`，排序保留数组。 算法对`[2,2],[2,2],[2,2]`，给出总和`6`。 输出是正确的并且与原始顺序无关。 

当大数与小数配对时，例如`[1, 2, 3, 100]`，排序确保`1`与`2`和`3`和`100`，最大化最小值之和`4`。 任何替代配对都会降低总分，从而确认算法能够以最佳方式处理这种情况。
