 ## 解决方案
 ## 问题理解

 对于每个二进制模式$p$，我们定义$f(p)$作为最小数量`1`s 在另一个二进制字符串中$q$的长度相同，使得每个位置$p$可以通过查看某个区间来“证明”其值$q$包含该位置。 

任务不是计算$f$对于单一模式。 我们得到一个二进制字符串$s$，我们必须求和$f$的所有子串$s$。 

所有测试用例的总长度最多为$10^6$。 有$O(n^2)$子字符串，因此任何单独评估子字符串的方法都是立即不可能的。 甚至$O(n \sqrt n)$在这种规模下会感到不舒服。 目标是每个测试用例的线性时间。 

问题的微妙部分是理解什么$f(p)$真正的意思是。 涉及模态的定义看起来很复杂，但是简化之后，问题就变成了一条线上的覆盖问题。 

考虑模式`111`。 

天真的阅读表明我们可能需要三个`1`进入$q$。 事实上，一`1`就足够了。 将其放在中间：`010`。 图案的每个位置都在距该位置的距离之内`1`，这足以使`1`包含位置的某个区间上的众数。 

现在考虑`1011`。 

一`1`最多可以覆盖三个连续位置，因此最左边和最右边的组不能同时被单个放置覆盖。 正确的值为$2$。 

一个常见的错误是认为模式包含的位置`0`施加对称约束。 他们没有。 减少后，仅包含以下位置：`1`事情。 

## 方法

 蛮力方法是枚举每个子串，计算$f$根据定义，并将结果添加到答案中。 

即使我们以某种方式计算$f$对于一个子串，在线性时间内，有$O(n^2)$子串。 和$n=10^6$，这是完全不可行的。 

关键的观察结果是模态条件有一个非常简单的结果。 

采取立场$i$在哪里$p_i=1$。 一个`1`是二进制区间的众数，如果该区间至少包含同样多的数`1`作为`0`s。 单个`1`已经满足这个了。 另外，长度为 2 的区间包含 1`1`和一个`0`具有两个值作为模式。 

结果，一个职位需要`1`满足当且仅当存在`1`在$q$距它最多一个距离。 单个`1`在$q$恰好覆盖了模式的三个位置：它自己的位置和它的两个邻居。 这将问题减少到覆盖所有`1`图案的位置，间隔长度为三。 

所以$f(p)$恰好是每个中心所需的最小数量`1`的位置$p$距离某个中心之一不远。 

在一条线上，最优贪心策略是标准的。 取最左边未覆盖的`1`，尽可能靠右放置一个中心，它覆盖了三个位置。 

剩下的挑战是对所有子字符串求和而不枚举它们。 

贪婪盖的结构给出了非常紧凑的DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$子串或更糟 | 取决于实施 | 太慢了 |
 | 最佳DP |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 让$$dp[i] = \sum_{l=0}^{i} f(s[l\dots i]).$$换句话说，$dp[i]$是在位置结束的所有子串的总贡献$i$。 

### 1.办案$s[i]=0$追加尾随`0`不会创建需要覆盖的新位置。 

对于每一个开始$l$,$$f(s[l\dots i]) = f(s[l\dots i-1]).$$因此$$dp[i] = dp[i-1].$$### 2. 办案$s[i]=1$取任意子串$s[l\dots i]$。 

它最右边的所需位置是$i$。 任何最佳掩护都必须使用一个中锋来掩护该位置。 

贪婪布局覆盖仓位$i-2,i-1,i$。 放置此中心后，右侧的所有内容$i-3$已经处理了。 

所以$$f(s[l\dots i]) = 1 + f(s[l\dots i-3]).$$如果$i-3<l$，第二项为零。 

### 3. 对所有起始位置求和

 有$i+1$可能的开始。 

每个子串结束于$i$贡献额外的$1$从新放置的中心。 

这给出了术语$$i+1.$$其余部分完全贡献$$dp[i-3].$$因此$$dp[i] = (i+1)+dp[i-3]$$什么时候$s[i]=1$。 

### 4. 积累答案

 最终的答案是$$\sum_i dp[i].$$### 为什么它有效

 不变的是每个中心恰好覆盖它周围的三个位置。 当子串最右边的字符是`1`，必须为最右边未覆盖的块保留一个中心。 贪心总是放置该中心，以便它覆盖左侧的最大可能范围。 删除长度为 3 的覆盖后缀后，剩下的问题与较短子字符串上的原始问题相同。 

这会创建精确的分解，而不仅仅是近似。 每个最优覆盖对应于缩短子串的一个最优覆盖加上一个新中心，反之亦然。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    s = input().strip()

    dp = [0] * n

    if s[0] == '1':
        dp[0] = 1

    ans = dp[0]

    for i in range(1, n):
        if s[i] == '0':
            dp[i] = dp[i - 1]
        else:
            dp[i] = i + 1
            if i >= 3:
                dp[i] += dp[i - 3]

        ans += dp[i]

    print(ans)
```数组`dp`存储总和$f$覆盖以固定位置结尾的所有子字符串。 

当当前字符为`0`，这里结束的每个子字符串与之前一个位置结束的相应子字符串具有完全相同的值，因此我们只需复制`dp[i-1]`。 

当当前字符为`1`，每个在此结尾的子串都需要一个额外的覆盖中心。 这些新中心的总贡献是`i + 1`，每个可能的起始位置都有一个。 未覆盖的余数正是以结尾的子串的集合`i - 3`，所以我们添加`dp[i - 3]`。 

所有值都适合 64 位整数。 最大可能的答案是$O(n^2)$，它完全在 Python 的整数范围内。

 ## 边缘情况

 考虑输入```
1
1
0
```唯一的子串是`0`。 没有位置需要掩护中心，所以$f=0$。 DP 开头为`dp[0]=0`，答案是`0`。 

考虑```
1
3
111
```粗心的解决方案可能会计算每个中心一个中心`1`并返回`10`覆盖所有子串。 正确的解释是一个中心覆盖三个相邻的位置。 递归产生：$$dp=[1,2,3]$$答案是`6`。 

考虑```
1
4
0000
```每个子字符串仅包含零。 递归重复复制前一个值：$$dp=[0,0,0,0].$$答案依然存在`0`。 

考虑```
1
4
1011
```决赛`1`不能被覆盖最左边的同一个中心覆盖`1`。 递归通过跳回三个位置来自动将问题分成独立的块`dp[i-3]`。 结果的答案是`11`，匹配最佳覆盖解释。
