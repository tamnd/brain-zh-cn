 ## 解决方案
 ## 问题理解

 我们得到一个循环数组，其中包含从 1 到 n 的数字排列。 有一个大小为 k 的固定窗口，代表缓冲区的“可见”部分，特别是任意时刻的前 k 个位置。 我们希望以从 1 到 n 递增的顺序“收集”数字，但只有当数字位于此可见窗口内时才能收集。 

唯一允许的操作是将整个数组向左或向右旋转一步。 每次旋转花费一个单位。 在任何轮换序列之后，我们可以按升序收集任何当前可见的数字，只要它们的值是下一个所需的值。 

任务是确定所需的最小旋转总数，以便我们能够成功地按顺序收集 1 到 n，并始终确保当我们达到值 x 时，它已在某个时刻被带入可见前缀。 

所有测试用例的约束 n 高达 10^6 意味着每个测试用例都有一个线性或接近线性的解决方案。 任何显式模拟旋转或重复搜索下一个位置的方法都会太慢，因为每次旋转都是 O(n)，并且可能需要 O(n) 次调整，从而导致 O(n^2)。 

天真的思维的一个微妙的失败案例是假设我们总是可以贪婪地旋转，以便下一个数字立即可见，然后继续前进。 这忽略了这样一个事实：一旦我们旋转固定一个数字，我们可能会破坏先前看到或跳过的数字的早期对齐。 

例如，考虑 n = 5，k = 2：

 输入：

 2 5

 2 3 4 5 1

 天真的贪婪策略可能会旋转直到 1 可见，然后关注 2，依此类推，但这会过度计算旋转次数，因为在单个旋转阶段后，多个连续目标可能已经落入窗口中。 

关键的困难在于旋转会同时影响所有位置，因此我们需要全局视图来了解每个值如何相对于移动窗口对齐。 

## 方法

 暴力解释将逐步模拟该过程。 我们维护当前的数组状态和指向我们需要的下一个值的指针。 如果该值已经在可见前缀中，我们将其标记为已收集。 否则，我们尝试向左和向右旋转，直到它出现在前缀中。 然后我们选择更好的方向并继续。 

从概念上讲，这是可行的，因为它始终遵守规则，但问题是每个缺失值可能需要 O(n) 次旋转才能对齐，并且有 n 个值，导致最坏情况的行为为 O(n^2)。 

关键的见解是我们实际上不需要模拟数组。 重要的是每个值在初始排列中的位置。 旋转相当于将所有索引移动一个以 n 为模的常数偏移量。 因此，我们不考虑数组的移动，而是考虑随时间变化的指针偏移量。 

现在考虑固定值 x。 它位于某个位置 pos[x]。 全局移位后，如果 pos[x] 位于圆上长度为 k 的移动区间内，则 x 变得可见。 对于每个 x，我们只关心必须从当前对齐旋转多远，以便 pos[x] 进入窗口。 一旦收集到 x，窗口位置可以进一步移动，但我们希望最小化总移动。 

关键的结构观察是，最优策略永远不需要考虑每个元素的任意旋转。 相反，我们只关心窗口被调整到足以使下一个所需值变得可见的转换。 在这些事件之间，多个连续值可能已经位于窗口中，这意味着不会产生任何成本。

因此，我们将问题转化为在圆上维护当前的“窗口间隔”，并且对于按升序排列的每个值，计算最小旋转距离以使其位置进入该间隔。 我们总是选择最接近的方向（左或右），因为旋转在周期上是对称的。 

这将问题简化为跟踪圆形线上的位置并更新滑动窗口，这可以使用模运算在线性时间内完成。

 | ---| ---| ---| ---|
 | 暴力模拟| O(n^2) | O(n^2) | O(n) | 太慢了 |

 ## 算法演练

 1. 构建数组`pos`在哪里`pos[x]`存储排列中值 x 的索引。 这让我们可以在 O(1) 中访问每个值的位置。 原因是我们只关心每个数字的位置，而不是完整的演化数组。 
2. 维护一个变量`shift`表示数组从其初始状态旋转了多远。 我们解释与此移位相关的所有内容，而不是物理旋转阵列。 
3. 在这个移动的坐标系中保持当前的可见窗口。 如果shift为s，则可见段对应索引`[s, s + k - 1]`模数 n. 这给出了检查某个值当前是否可收集的直接条件。 
4. 将 x 从 1 迭代到 n。 对于每个 x，计算其在移位下的当前有效位置，即`(pos[x] - shift) mod n`。 这给出了 x 在当前坐标系中的位置。 
5. 如果 x 已经在可见窗口内，则继续而不增加成本。 这很重要，因为连续的值无需额外旋转即可收集。 
6. 如果 x 不可见，请计算将其带入窗口所需的最小旋转次数。 由于我们可以向左或向右旋转，因此我们以圆形方式计算到窗口最近边界的距离，并将该成本添加到答案中。 然后更新`shift`相应地，x 在下一步中变得可见。 
7. 收集 x 后，我们使用更新后的移位继续进行 x + 1。 不变量是所有先前收集的元素在较早的时刻都是有效的，并且我们只在 x 中向前移动。 

### 为什么它有效

 在任何时刻，系统状态都可以通过单个旋转偏移来完全描述。 每次操作仅更改此偏移量，可见性由圆上的固定间隔确定。 由于排列是固定的，每个值都有一个确定的位置，我们唯一的自由是如何移动窗口。 贪心的决定是仅仅转移足以使下一个所需的值可见是最优的，因为任何额外的转移只会增加成本，而不会以减少以后所需操作的方式扩展未来的灵活性。 这是收集顺序是固定且独立于轮换历史这一事实的直接结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(a):
        pos[v] = i

    shift = 0
    ans = 0

    for x in range(1, n + 1):
        cur = (pos[x] - shift) % n

        if cur < k:
            continue

        # need to rotate so that cur enters [0, k-1]
        # best move is to bring it to k-1
        target = (cur - (k - 1)) % n
        ans += target
        shift = (shift + target) % n

    print(ans)

if __name__ == "__main__":
    solve()
```该实现依赖于将所有旋转压缩为单个模块化偏移变量。 关键的微妙之处在于解释移动坐标系中的可见性，而不是物理旋转阵列。 

表达式`(pos[x] - shift) % n`将固定位置转换为当前帧。 支票`cur < k`相当于测试该值是否已经在可见前缀之内。 如果不是，我们旋转得足够多，使元素与窗口的右边界对齐，从而最大限度地减少浪费的移动。 

的更新为`shift`累积轮换，确保未来元素的一致性。

 ## 边缘情况

 一种边缘情况是 k 等于 n。 在这种情况下，窗口始终覆盖整个缓冲区，因此每个数字都可以立即收集，无需任何旋转。 该算法处理这个问题是因为每个`cur`总是小于 k，因此不会添加任何移位。 

另一种边缘情况是 k 等于 1，其中只有一个位置可见。 在这种情况下，每个值必须单独对齐到位置 0。该算法正确地累积每个元素所需的最小圆形距离，有效地模拟每一步的最佳对齐。 

第三种边缘情况是排列已经排序。 然后，所有值最初在位置 0 到 n-1 中按递增顺序排列，并且根据 k，许多连续值在第一次对齐后已经落入可见前缀中。 基于移位的表示自然地捕获了这一点，因为早期旋转向前传播可见性而无需冗余操作。
