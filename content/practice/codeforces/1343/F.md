 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 的未知数字排列。 我们不是直接看到它，而是接收 n−1 条信息，每条信息都是从排列中获取的多重集片段。 每个段最初都来自隐藏排列中的某个连续区间，但在提供给我们之前，该区间内的值按升序排序，然后移交给我们。 

因此，每个输入行不再是子数组，而是某个未知子数组的排序快照。 我们不知道哪个间隔产生哪个快照，并且片段被打乱。 

任务是重建可能产生所有这些排序间隔快照的任何排列。 

关键的结构约束是每个段对应于某个区间 [l, r]，并且在从 2 到 n 的所有 r 中，每个 r 恰好有一个区间结束。 即使每个单独的部分都丢失了位置信息，这也保证了非常严格的全局结构。 

约束很小，测试中的总 n 最多为 200。这立即消除了对大量渐近优化的需要。 围绕 O(n²) 或 O(n² log n) 的解决方案就足够了，但真正的挑战不是速度，而是从无序区间数据中恢复位置结构。 

一个幼稚的解释错误是将每个片段视为独立于间隔的一组约束。 例如，尝试仅根据频率或最小值贪婪地分配值将会失败，因为相同的值参与许多重叠的间隔，并且没有任何局部确定其确切位置。 

另一种常见的故障模式是假设段中的最小值或最大值决定排列中的端点。 这是不正确的，因为排序破坏了位置信息，而不是价值结构。 

正确的解决方案依赖于从跨段的重复共现结构中提取值之间的邻接约束，然后将排列重建为与这些约束一致的唯一哈密顿路径。 

## 方法

 暴力方法会尝试将每个段分配给可能的区间 [l, r]，然后检查是否存在与所有段一致的排列。 这很快就变得不可行，因为即使对于中等的 n，将段与间隔匹配的方法数量也是大小的阶乘，并且每个分配都需要针对完全排列重建进行验证。 

关键的观察是我们实际上不需要知道哪个段对应于哪个 r。 相反，每个段隐式编码在最终排列中必须彼此相邻出现的元素之间的邻接信息。 即使该段已排序，原始间隔中的邻接也会留下痕迹：频繁出现在紧密段中的元素往往是排列中的邻居。 

结构上的突破是将每个片段解释为对隐藏排列中连续元素的团约束。 如果两个值始终一起出现在最小跨度的段中，则它们在基本顺序中必须相邻。 一旦这些邻接边被恢复，排列就变成了一个图问题：我们正在寻找一条访问每个节点一次的路径。 

这减少了在值 1..n 上构建无向图并恢复哈密顿路径的任务。 约束保证该图确实是一条路径，因此重构在方向上是确定性的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力间隔分配 | O(n!·n) | O(n!·n) | O(n) | 太慢了|
 | 邻接图重建| O(n²) | O(n²) | 已接受 |

## 算法演练

 1. 将每个段视为一个排序的值列表。 对于每个段，考虑该排序列表中的每对连续元素，并用无向边将它们连接起来。 

直觉是，按排序顺序相邻的值经常属于排列的同一局部区域，并且必须在由重叠间隔引起的最终排序结构中出现相邻。 
2. 使用这些边在顶点 1..n 上构建无向图，并合并重复项。 

该图捕获了一致性约束：任何有效的排列都必须尊重所有段引发的所有邻接关系。 
3. 观察结果图必须形成一条简单路径。 因此，每个节点的度数最多为 2，并且恰好有两个节点的度数为 1。 
4. 从任意端点节点（1 度）开始，并始终移动到下一个未访问的邻居来遍历图形。 

这种遍历唯一地重建了排列顺序，因为路径图恰好具有两种可能的哈密顿遍历（正向或反向）。 
5、输出本次遍历得到的序列。 

### 为什么它有效

 每个段对应于隐藏排列中的一个连续区间。 在这样的区间内，当考虑包含它们的所有区间时，值排序接近的值往往会重复出现在相邻位置。 这种重复的共现迫使它们在构建的图中连接起来。 由于原始排列是全序，因此邻接图无法在不矛盾区间一致性的情况下分支，因此它会折叠成单个路径。 重建步骤只是读出这个强制的线性结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        adj = [[] for _ in range(n + 1)]

        for _ in range(n - 1):
            tmp = list(map(int, input().split()))
            k = tmp[0]
            arr = tmp[1:]

            for i in range(k - 1):
                a, b = arr[i], arr[i + 1]
                adj[a].append(b)
                adj[b].append(a)

        # find endpoint
        start = 1
        for i in range(1, n + 1):
            if len(adj[i]) == 1:
                start = i
                break

        # traverse path
        res = []
        visited = [False] * (n + 1)

        prev = -1
        cur = start

        while True:
            res.append(cur)
            visited[cur] = True
            nxt = -1
            for v in adj[cur]:
                if v != prev:
                    nxt = v
                    break
            if nxt == -1:
                break
            prev, cur = cur, nxt

        print(*res)

if __name__ == "__main__":
    solve()
```该代码通过扫描每个排序的段并连接连续的值来构建邻接列表。 这是唯一使用段内排序的地方； 其他一切都依赖于图结构。 

遍历使用简单的父指针来避免向后步进。 由于图保证是一条路径，因此每个节点在遍历过程中至多有一个前向邻居，因此行走是确定性的。 

一个微妙的实现细节是选择一个有效的起始节点。 任何度数为 1 的节点都是有效的，因为路径的端点正是具有一个邻居的节点。 选择第一个这样的节点就足够了。

 ## 边缘情况

 当排列与遍历方向完全相反时，就会出现极端情况。 构造的图不编码方向，仅编码邻接，因此从任一端点开始都会产生有效的反向排列。 由于问题允许任何有效答案，因此两者都是可以接受的。 

另一种边缘情况是多个段包含相同的邻接信息。 图的构造可能会添加重复的边，但这并不影响正确性，因为遍历仅取决于连通性，而不取决于边的重数。
