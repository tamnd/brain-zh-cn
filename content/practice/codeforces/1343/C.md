 ## 解决方案
 ## 问题理解

 我们给定一个整数序列，包括正数和负数，并且需要构造一个其元素严格符号交替的子序列。 在所有达到最大可能长度的子序列中，我们被要求找到总和最大的一个。 每个测试用例的输出就是该总和。 

每个测试用例提供元素数量，后跟序列本身。 约束是巨大的：跨测试用例的所有序列长度的总和不超过 200,000，因此任何解决方案都必须在每个测试用例的线性时间内运行。 二次解（例如检查每个可能的子序列）是不可行的。 

当连续元素具有相同符号时，会出现微妙的边缘情况。 例如，如果输入是`[1, 2, 3, -1, -2]`，最大交替子序列将在切换到负数之前选择最大的正数，然后在再次切换之前选择最大的负数。 简单地交替每个元素将无法使总和最大化。 当所有元素具有相同符号时，会出现另一种棘手的情况，例如`[-1, -2, -3]`，其中最长交替子序列的长度为一，正确答案是最大的元素`-1`。 

## 方法

 蛮力方法是生成所有可能的子序列，检查哪些子序列的符号交替，然后选择长度最大且总和最大的子序列。 这是正确的，但完全不切实际：生成子序列的时间复杂度为 O(2^n)，并且 n 最大可达 2 × 10^5。 

实现有效解决方案的关键观察是，在具有相同符号的连续数字段中，我们只需要最大的数字。 包含较小的数字将减少总和，而不会延长交替子序列的长度。 因此，序列可以被压缩为具有相同符号的连续数字的“块”，并且对于每个块我们选择最大元素。 压缩后，只需按交替顺序对这些最大元素求和即可获得最佳解决方案。 

因此，最佳方法通过迭代序列、维持当前符号块的最大值并在符号发生变化时将其添加到总和中，以线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化`sum_total`为零。 这将存储所选交替子序列的总和。 
2. 设置`current_max`到序列的第一个元素。 这跟踪当前符号块中最大的元素。 
3. 从第二个元素开始迭代序列。 对于每个元素：

 1. 如果其符号匹配`current_max`， 更新`current_max`到两者中较大的一个。 这确保我们只保留当前符号块中最大的数字。 
2. 如果其符号不同，则添加`current_max`到`sum_total`并设置`current_max`对于这个新元素，开始一个新的符号块。 
4.迭代结束后，添加最后一个`current_max`到`sum_total`。 这处理最后一个块。 
5. 打印`sum_total`。 

为什么它有效：不变的是在任何时候，`current_max`保存当前连续符号块的最大元素。 由于交替子序列需要切换每个元素的符号，因此选择每个块中最大的元素可以最大化总和，而不会减少子序列长度。 这保证了结果是最大长度交替子序列的最大和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    sum_total = 0
    current_max = a[0]
    
    for i in range(1, n):
        if (a[i] > 0) == (current_max > 0):
            current_max = max(current_max, a[i])
        else:
            sum_total += current_max
            current_max = a[i]
    
    sum_total += current_max
    print(sum_total)
```每个部分都直接来自算法。`current_max`保留当前符号块的最大值。 比较`(a[i] > 0) == (current_max > 0)`检查当前元素是否与前一个块具有相同的符号。 添加`current_max`最后确保最后一个块被考虑在内。 这可以避免相差一的错误，并且适用于完全正或负的序列。
