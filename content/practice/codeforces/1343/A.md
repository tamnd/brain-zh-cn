 ## 解决方案

 ## 问题理解

 我们收到了一些糖果包装纸，并且我们知道它们来自非常特定的购买模式。 第一天，Vova 买了一些整数糖果，称之为$x$。 接下来的每一天，他都会将前一天的购买量增加一倍，因此购买顺序如下$x, 2x, 4x, \dots, 2^{k-1}x$未知的天数$k$， 在哪里$k > 1$。 

如果我们将全天购买的所有糖果相加，我们会得到：$$n = x(1 + 2 + 4 + \dots + 2^{k-1})$$括号内的几何级数总是折叠为$2^k - 1$，所以约束相当于找到任何分解$n$这样：$$n = x(2^k - 1), \quad k > 1, \quad x \ge 1$$任务不是恢复原来的状态$x$和$k$，但只是输出任何有效的$x$可能会产生给定的$n$对于一些有效的$k$。 

约束允许最多$10^4$测试用例和$n$最多$10^9$，这会立即排除任何尝试枚举所有对的解决方案$(x, k)$或者为每个测试用例以简单的嵌套方式模拟该过程。 直接暴力破解$k$仍然很小，因为$2^k - 1$呈指数增长，所以$k$最大的最多也就30个左右$n$。 这种观察至关重要。 

一个微妙的边缘情况是$k$必须严格大于 1。如果有人忘记了这一点，他们可能会错误地允许$k = 1$，这将使$n = x$，但这在问题中是无效的。 另一个问题正在尝试修复$x = 1$总是; 这仅在以下情况下有效$n$本身是梅森数，一般情况下会失败。 

## 方法

 暴力方法会尝试一切可能的方法$k$，计算总和因子$2^k - 1$，并检查是否$n$可以被它整除。 如果是的话，那么$x = n / (2^k - 1)$是一个有效的答案。 这是有效的，因为公式是精确的，并且每个有效的构造都对应于一些$k$。 问题是性能仍然受到数量的限制$k$我们测试的值。 

关键的观察是几何乘数$2^k - 1$增长速度极快。 自从$n \le 10^9$，我们最多只需要测试 30 个左右的值$k$。 这将问题变成每个测试用例的一个小循环。 对于每个$k$，我们检查整除性并立即返回一个有效的$x$。 

无需搜索所有解决方案或进一步优化。 接受任何有效的对，因此第一个成功的$k$就足够了。

 | ---| ---| ---| ---|
 | 蛮力胜过一切$x, k$|$O(n \log n)$|$O(1)$| 太慢了|
 | 全部尝试$k$最多 30 |$O(t \log n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 对于每个测试用例，请阅读$n$。 目标是找到代表$n = x(2^k - 1)$。 
2. 迭代可能的值$k$，从$k = 2$因为问题明确禁止$k = 1$。 
3. 对于每个$k$，计算乘数$m = 2^k - 1$。 
4.如果$m > n$，停止检查更大的$k$，因为所有未来的乘数只会增长。 
5. 如果$n \mod m = 0$, 计算$x = n / m$并立即输出。 

这种贪婪停止起作用的原因是，一旦几何因子超过$n$，就不能再分了。 

### 为什么它有效

 每个有效配置都对应于以下形式的因式分解$n = x(2^k - 1)$。 该算法系统地枚举了第二个因素的所有可能值$2^k - 1$可以适合$n$。 由于这些值严格随着$k$，如果存在的话，我们保证会遇到正确的。 一旦找到，除法恢复唯一对应的$x$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        
        k = 2
        power = 3  # 2^2 - 1
        
        while power <= n:
            if n % power == 0:
                print(n // power)
                break
            k += 1
            power = (1 << k) - 1

solve()
```实现直接反映了推导。 变量`power`曲目$2^k - 1$，从$k = 2$，对应于$3$。 循环增加$k$直到乘数超过$n$，确保我们只测试可行的候选人。 

一个常见的错误是在循环内使用幂运算从头开始重新计算幂，这是不必要的，但仍然足够快。 另一个微妙的问题是从$k = 1$，这会引入无效的情况$2^1 - 1 = 1$并错误地允许$x = n$。 

## 工作示例

 我们跟踪样本中的两个输入。

 | 2 | 3 | 是的 | 输出$21 / 3 = 7$|

 该算法立即停止，因为$21$可以整除$3$。 这对应于$k = 2, x = 7$，它重建了$7 + 14 = 21$。 

### 示例 2：$n = 28$| k |$2^k - 1$| 可除的？ | 行动|
 | ---| ---| ---| ---|
 | 2 | 3 | 没有| 继续 |

 这会产生$k = 3, x = 4$，对应于$4 + 8 + 16 = 28$。 

这些痕迹表明该算法不需要搜索所有分解，只需要找到一个有效的几何除数。

 ## 边缘情况

 一个关键的边缘情况是当$n$本身就是形式$2^k - 1$。 例如，$n = 7$。 该算法开始于$k = 2$, 检查$3$，移动到$7$，并立即发现整除性，产生$x = 1$。 这对应于从 1 开始的完整几何序列。 

另一种情况是当$n$不能被小乘数整除，但稍后可以整除$k$， 例如$n = 28$。 循环跳过$k = 2$自从$28 \bmod 3 \neq 0$，然后成功$k = 3$带乘数$7$，产生$x = 4$。 该算法不会提前提交，因此不会错过后来的有效分解。 

最后，对于大$n$喜欢$999999999$，循环仍然很快终止，因为$2^k - 1$超过$n$在大约 30 次迭代内，无论输入分布如何，都保证有界运行时间。
