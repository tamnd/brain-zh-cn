 ## 解决方案
 ## 问题理解

 我们得到一个 n × n 矩阵和一系列操作。 每个操作都使用其左上角和右下角坐标选择一个方形子矩阵，然后对该子矩阵应用一个几何变换。 这些变换是标准的图像式操作：顺时针旋转 90 度、水平翻转、垂直翻转以及穿过两条对角线的反射。 

按顺序应用所有操作后，必须打印最终矩阵。 

关键细节是操作仅适用于子矩阵，而不是整个网格，并且同一单元格可以涉及许多重叠的变换。 输出取决于所有转换的累积效果。 

约束允许 n 最多 500 次和最多 100 次操作。 因此，为每个操作重建受影响的子矩阵的直接模拟是合理的，因为每个操作最大可能的工作是在 500 x 500 的区域上，大约有 250,000 个单元，并且最多重复 100 次，提供大约 2500 万个单元更新。 

边缘情况主要来自子矩阵内部如何应用变换。 

第一个微妙的问题是旋转的正确性。 如果我们在旋转时就地覆盖矩阵，我们会在移动之前破坏值。 例如，在没有临时缓冲区的情况下原地旋转 3 x 3 块将覆盖稍后在旋转映射中仍需要的条目。 

另一个问题是索引一致性。 输入是从 1 开始的，因此未能转换为从 0 开始的索引会导致很难检测到的离一损坏，因为结果可能看起来仍然结构化但不正确。 

最后，对角线翻转需要仔细的坐标映射。 全局交换行和列而不是在子矩阵内交换行和列的简单实现将破坏矩阵的不相关部分。 

## 方法

 强力解释直接遵循问题陈述：对于每个操作，提取子矩阵，构建新的转换版本，然后将其写回。 

这是可行的，因为每个变换都是正方形区域内坐标的固定排列。 对于大小为 k 的子矩阵，我们可以在 O(1) 中计算每个元素的新位置，因此重建子矩阵的成本为 O(k²)。 由于每个单元仅在处理其包含的子矩阵时才被重写，因此总工作量受其受影响区域大小平方的所有操作之和的限制。 

最坏的情况发生在每个操作都触及完整的 n × n 矩阵时。 那么每个操作的成本为 O(n²)，当 q 达到 100 时，这将变为 O(100·500²)，这大约是 2500 万次分配。 这在 Python 中是可以接受的。 

关键的观察是不需要任何全局坐标跟踪或惰性变换组合。 运算次数少，直接重新计算更简单、安全。 任何维护每个单元的符号变换的尝试都会变得不必要的开销，并增加实现的复杂性，而不会提高此约束机制中的渐近性能。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子矩阵重建| O(q·k²) | O(q·k²) | O(k²) | 已接受 |
 | 最佳直接模拟| 最坏情况 | O(q · n²) O(n²) | 已接受 |

 在这个问题中，两种方法都会收敛，因为约束足够小，直接的模拟已经是最佳的。 

## 算法演练

 我们将矩阵维持在当前状态并直接应用每个操作。

1. 读取矩阵并将其转换为可变结构。 这允许在每次转换后进行就地更新。 
2. 对于每个操作，将坐标从基于 1 的索引转换为基于 0 的索引。 这可确保所有进一步的索引都符合 Python 数组约定并防止边界移位。 
3. 将操作定义的子矩阵提取到临时缓冲区中。 此步骤隔离该区域，以便转换不会覆盖计算过程中仍需要的值。 
4. 构造一个与子矩阵大小相同的新矩阵。 
5. 根据变换类型填充新矩阵。 对于旋转，子矩阵中位置 (i, j) 的每个元素都会移动到 (j, k-1-i)。 对于水平和垂直翻转，索引沿相应的轴反转。 对于对角线反射，行索引和列索引根据使用的对角线进行适当反转的交换。 
6. 将变换后的子矩阵写回到原始矩阵的相同坐标处。 
7. 重复此操作，直至处理完所有操作。 

所有更新后，打印最终矩阵。 

### 为什么它有效

 每个操作都是对所选方形区域的单元的双射，这意味着每个元素恰好移动到一个新位置，并且每个位置恰好接收一个元素。 因为我们在写回每个子矩阵之前完全重建了它，所以我们完全按照变换的定义保留了这种一对一的映射。 由于操作是按顺序应用的，并且每个步骤都使用上一步中完全更新的矩阵，因此最终状态按顺序匹配所有转换的组合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
a = [list(map(int, input().split())) for _ in range(n)]

def apply_op(x0, y0, x1, y1, t):
    x0 -= 1
    y0 -= 1
    x1 -= 1
    y1 -= 1
    k = x1 - x0 + 1

    tmp = [[0] * k for _ in range(k)]

    for i in range(k):
        for j in range(k):
            tmp[i][j] = a[x0 + i][y0 + j]

    res = [[0] * k for _ in range(k)]

    if t == 1:
        for i in range(k):
            for j in range(k):
                res[j][k - 1 - i] = tmp[i][j]

    elif t == 2:
        for i in range(k):
            for j in range(k):
                res[i][k - 1 - j] = tmp[i][j]

    elif t == 3:
        for i in range(k):
            for j in range(k):
                res[k - 1 - i][j] = tmp[i][j]

    elif t == 4:
        for i in range(k):
            for j in range(k):
                res[j][i] = tmp[i][j]

    elif t == 5:
        for i in range(k):
            for j in range(k):
                res[k - 1 - j][k - 1 - i] = tmp[i][j]

    for i in range(k):
        for j in range(k):
            a[x0 + i][y0 + j] = res[i][j]

for _ in range(q):
    x0, y0, x1, y1, t = map(int, input().split())
    apply_op(x0, y0, x1, y1, t)

for row in a:
    print(*row)
```通过将每个操作隔离到辅助函数中，实现完全遵循算法。 临时缓冲区`tmp`是必要的，因为所有转换都取决于子矩阵的原始配置，并且就地更新将覆盖以后分配所需的值。 

每个变换情况都编码一个直接坐标映射。 例如，旋转情况使用 (i, j) 到 (j, k-1-i) 的映射，这对应于顺时针旋转正方形。 对角线情况交换索引，反映在主对角线或反对角线上。 

必须注意的是，所有索引在每次操作开始时都一致地转换为基于 0 的形式，并且写回`a`仅在计算完整变换块之后发生。

 ## 边缘情况

 1 x 1 子矩阵测试转换是否错误地尝试将单元格移动到其自身上或索引超出范围。 该算法处理此问题是因为每个映射都会将 (0,0) 发送回 (0,0)，因此矩阵保持不变。 

全网格运行重复多次考验积累。 由于每个操作在下一个操作之前完全重建矩阵，因此除了有意的组合之外，变换之间不存在干扰。 

重叠子矩阵测试隔离的正确性。 由于每个操作在写回之前都会复制到临时缓冲区中，因此在同一操作期间不会部分重用之前的更新，从而防止中间值损坏。
