 ## 解决方案
 ## 问题理解

 我们站在一个 2D 平面上，有一个隐藏点代表一辆汽车。 我们给出了一个关键参数，半径`r`，我们可以交互式地在平面上的任何位置移动一个点并收到一个二进制答案：我们当前的位置是否在距离内`r`隐藏的汽车与否。 

我们从原点开始`(0, 0)`并且我们保证这个起点在检测圈内。 每个查询都让我们重新定位到任何真实坐标，并观察我们是否仍在以未知汽车位置为中心的圆内。 任务是使用最多 300 个查询来确定该圆心的精确坐标，然后以足够的精度输出。 

关键的结构事实是隐藏对象完全由已知半径的欧几里得圆决定。 我们不是在网格或图形上搜索，而是在连续几何中搜索，其中每个查询都在磁盘中提供成员资格测试。 

这些约束清楚地表明，任何密集采样或网格重建都是不可能的。 即使在 20000 x 20000 平方上以 0.01 分辨率对平面进行粗略离散化，也需要大约 10^10 次评估，远远超过 300 次查询。 唯一可行的路径是利用圆的几何结构并将问题简化为恒定数量的连续一维搜索。 

如果人们认为单向搜索就足够了，就会出现一个微妙的问题。 从圆内的起点开始，沿着一条射线移动只能识别出一个边界点，但无限多个圆心可以对应于该边界点。 另一种失效模式是假设绕原点对称，这无法保证并导致不正确的几何重建。 

## 方法

 蛮力的想法是对平面上的点进行采样，并尝试通过检测内部和外部区域来“勾勒出”圆的轮廓。 人们可能会想象扫描网格或从原点向多个方向执行径向采样。 虽然每个查询都很便宜，但所需的方向数量会不断增加，直到角分辨率足够细以定位中心，这实际上成为一个连续搜索问题，在 300 个查询内没有明确的终止界限。 这会失败，因为圆边界具有无限分辨率，因此任何固定角度离散化都可能会错过正确的中心位置。 

关键的观察是我们不需要完整的边界。 单个边界点已经编码了强大的几何信息：如果我们知道一个点`P`在圆和半径上`r`，那么中心必须正好位于距离`r`从`P`。 这将未知数从二维中的点减少到两个圆的交点。 

剩下的挑战是如何获得精确的边界点。 这就是沿光线的单调性变得有用的地方。 如果我们固定一个方向向量并从原点向外移动，答案最初是“内部”，最终会恰好一次变成“外部”，因为原点位于圆内部，并且直线与圆相交在一条线段中。 这将创建沿任何射线的单调谓词，可以进行二分搜索。 

一旦从两个独立方向找到两个边界点，圆心就是两个半径圆的交点`r`以这些边界点为中心。 最多有两个交点，通过检查哪个候选点位于原点周围的圆内来确定正确的交点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 强力采样| O(N) 查询，其中 N ≫ 300 | O(1) | O(1) | 太慢了 |
 | 射线+二分查找+几何| O(log R) 查询 | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们依赖于原点严格位于圆内的事实，因此来自原点的每条射线与边界恰好相交一次。 

1.固定一个方向向量，例如`(1, 0)`。 考虑表格的要点`(t, 0)`和`t ≥ 0`。 在`t = 0`，我们在圈内。 作为`t`增加，存在一个唯一的阈值`t0`状态从内部切换到外部。 这是沿 x 轴方向的边界点。 
2. 执行二分查找`t`在足够大的间隔内，例如`[0, 20000]`。 每一步查询中点`(mid, 0)`并根据响应是内部还是外部来缩小间隔。 单调转换保证了二分查找的正确性。 
3. 设结果边界点为`P1`。 
4. 在独立方向上重复相同的过程，例如`(0, 1)`，得到第二个边界点`P2`。 这确保了我们不会受限于简并的单线重建。 
5. 我们现在知道中心`C`满足：```
|C - P1| = r
|C - P2| = r
```这意味着`C`位于以`P1`和`P2`，都具有半径`r`。 
6. 使用标准几何公式计算这些圆的两个可能的交点。 
7. 对于每个候选中心，检查哪一个满足原始条件：在距离内`r`从原点开始（由于原点保证在圆内，因此只有正确的中心才能在重建约束下保持一致性）。 

### 为什么它有效

 正确性取决于两个不变量。 首先，沿着从圆内一点开始的任何射线，隶属谓词从内到外恰好转换一次，这使得二分搜索在连续域上有效。 其次，圆的任何两个不同的边界点唯一地确定其中心直至反射模糊，并且原点位于圆内部的附加约束消除了不正确的交点候选。 这些属性共同确保重建点必须与真实中心重合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import math

EPS = 1e-7

def ask(x, y):
    print("?", x, y)
    sys.stdout.flush()
    return int(input().strip())

def binary_search_direction(dx, dy):
    lo, hi = 0.0, 20000.0
    
    # ensure hi is outside
    if ask(hi * dx, hi * dy) == 1:
        # extremely unlikely, but just in case expand
        while ask(hi * dx, hi * dy) == 1:
            hi *= 2
    
    for _ in range(60):
        mid = (lo + hi) / 2
        if ask(mid * dx, mid * dy) == 1:
            lo = mid
        else:
            hi = mid
    
    return lo * dx, lo * dy

def circle_intersections(p1, p2, r):
    x1, y1 = p1
    x2, y2 = p2
    
    dx, dy = x2 - x1, y2 - y1
    d = math.hypot(dx, dy)
    
    if d < 1e-12:
        return []
    
    midx = (x1 + x2) / 2
    midy = (y1 + y2) / 2
    
    h = math.sqrt(max(0.0, r*r - (d/2)**2))
    
    ux, uy = -dy / d, dx / d
    
    c1 = (midx + h * ux, midy + h * uy)
    c2 = (midx - h * ux, midy - h * uy)
    
    return [c1, c2]

def dist(x, y):
    return math.hypot(x, y)

def main():
    r = float(input().strip())
    
    p1 = binary_search_direction(1.0, 0.0)
    p2 = binary_search_direction(0.0, 1.0)
    
    candidates = circle_intersections(p1, p2, r)
    
    for cx, cy in candidates:
        if dist(cx, cy) <= r + 1e-6:
            print("!", cx, cy)
            sys.stdout.flush()
            return

if __name__ == "__main__":
    main()
```该解决方案首先读取半径，然后使用沿正交轴的二分搜索独立提取两个边界点。 每次搜索都依赖于沿射线位于圆内的单调特性。 一旦边界上的两点被固定，标准圆相交几何就会恢复中心候选，并通过验证与已知内点的一致性来选择正确的中心。 

一个微妙的实现细节是所有几何运算都必须容忍浮点错误。 二分查找不需要极高的精度，因为最终的圆交会细化结果。 60 次迭代足以使位置误差远低于`1e-6`输出条件所需的容差。

 ## 边缘情况

 一种边缘情况是圆相对于搜索间隔非常大。 在这种情况下，二分查找上限可能仍然在圆内，因此实现必须动态扩展区间。 代码通过加倍处理这个问题`hi`直到找到外部点，确保单调段被正确括起来。 

当两个选择的方向产生几乎共线的边界点时，会出现另一种边缘情况，这可能会导致圆相交的数值不稳定。 该算法通过使用正交方向来避免这种情况`(1, 0)`和`(0, 1)`，确保路口系统状况良好。 

最后的边缘情况是选择正确的交集候选时的浮点精度。 由于两个候选解都是有效的几何解，因此只有原点位于圆内的附加约束才能消除它们的歧义。 该检查使用较小的 epsilon 余量来防止由于舍入错误而被拒绝。
