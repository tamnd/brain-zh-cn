 ## 解决方案
 ## 问题理解

 我们得到了一个完整的矩阵，描述了每对 8 支球队之间的结果概率。 对于任意两支球队$i$和$j$, 条目$a_{i,j}$给出的概率是$i$失败$j$在单场比赛中，互补概率$a_{j,i}$确保其中一人获胜。 比赛是独立的，两队之间的每次交锋都会根据这些固定的概率来解决。 

锦标赛结构是固定且不对称的。 8支球队分为两组，A组有5支球队，B组有3支球队。 在 A 组中，进行一个预定义的分组（如声明中缺少的图所示），该分组中的一场特定比赛称为“G3 比赛”。 G3 比赛的获胜者是晋级下一阶段的三支队伍之一。 我们的任务是计算 BLG（第 5 队）成为 A 组 G3 比赛获胜者的概率。 

因此，关键输入不是单个游戏，而是完整的概率锦标赛，其中每种可能的比赛结果都可能发生，并且我们必须汇总所有可能的锦标赛演变。 

约束条件$t \le 1000$意味着我们必须为许多独立实例有效地重新计算这个概率。 每个实例只包含一个$8 \times 8$矩阵，所以任何解决方案$O(8^3)$,$O(2^8)$，或者甚至每个测试用例一个小的常数因子动态规划也是可以接受的。 任何试图天真地枚举所有锦标赛结果组合的行为都将呈指数级爆炸，超出了可行性。 

此类问题中的一个微妙问题是将比赛结果视为独立的，同时仍然尊重括号结构。 尝试随机“遍历”锦标赛或枚举比赛结果的所有排列的简单模拟将重复计算状态或错过回合之间的依赖关系。 另一个常见的错误是假设球队可以任意见面，而实际上，括号固定了谁和谁比赛以及何时比赛。 

例如，如果 BLG 和 G2 只能在固定分组的半决赛中相遇，那么允许他们在任何一轮比赛的幼稚模型都会严重扭曲概率。 正确的解决方案必须尊重确切的锦标赛树。 

## 方法

 暴力方法将枚举锦标赛分组中每场比赛的获胜者的所有可能分配。 由于每场比赛有两个结果，并且每轮有多个比赛，因此可能性总数随着比赛数量呈指数增长。 即使只有少数匹配，我们很快就能达到每个测试用例数千或数百万个状态，这对于$t = 1000$。 

然而，问题的结构并不是任意的。 比赛是固定括号的，这意味着整个过程形成了比赛的二叉树。 每个内部节点对应两个子括号之间的一场比赛，每个叶子是一个团队。 这使我们能够计算每个节点每个团队到达该节点的概率。 

关键的观察是我们不需要列举全球的结果。 相反，我们通过锦标赛树向上传播概率。 在任何比赛节点，如果我们已经知道球队到达左右子节点的概率分布，我们可以使用成对获胜概率将它们组合起来，以计算父节点的分布。 这将问题从指数枚举简化为固定树上的多项式传播。 

由于锦标赛结构固定且规模较小（只有 8 支球队），因此每个测试用例的动态规划大小都是恒定的。

 | 锦标赛括号树上的 DP |$O(8^2)$每个测试用例|$O(8)$| 已接受 |

 ## 算法演练

 我们将锦标赛视为一个固定的二叉树，其中叶子是球队，内部节点是比赛。 

### 步骤

 1. 将锦标赛分组构建为二叉树，其叶子对应于 8 支球队。 每个内部节点代表其左子树和右子树的获胜者之间的一场比赛。 该结构由问题陈述确定，不依赖于概率。 
2.对于树中的每个节点，维护一个概率分布数组$dp[node][i]$，代表团队的概率$i$到达该节点。 
3. 初始化叶节点，以便分配给该叶节点的团队存在的概率为 1，而所有其他团队的概率为 0。这编码了这样一个事实：每个团队都从括号中的一个位置开始。 
4. 自下而上处理树。 对于具有左子节点的内部节点$L$和右孩子$R$，计算每个团队的概率$i$通过考虑所有方式到达该节点$i$可能来自比赛的任何一方。 这取决于是否$i$来自左子树或右子树。 
5. 当两个孩子组合时，每对一组$i$和$j$，我们使用给定的矩阵概率$p_{i,j}$。 如果$i$来自左子树并且$j$从右子树开始，那么$i$失败$j$有概率$p_{i,j}$，贡献于$i$前进的概率。 对称地，$j$可以打败$i$。 
6. 贡献$dp[node][i]$是所有对手的总和$j$在相反的子树中：$dp[L][i] \cdot dp[R][j] \cdot p_{i,j}$，加上对称情况如果$i$来自右子树。 
7. 填充 A 组括号的根后，BLG 在 G3 比赛中获胜的概率就是在该特定节点分配给 BLG 的概率。 

### 为什么它有效

 每个内部节点代表其下锦标赛所有可能历史的完整分区。 节点上的 DP 状态准确地捕获了团队在该子组中幸存的概率分布。 由于匹配结果是独立的并且完全由成对概率决定，因此使用成对转换组合子项可以保持正确性。 每个可能的锦标赛结果都对应于通过此 DP 构造的一条路径，因此不会重复计算或省略任何场景。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a = []
        for _ in range(8):
            a.append(list(map(int, input().split())))
        
        # convert to probabilities
        p = [[x / 100.0 for x in row] for row in a]

        # dp[node][team]
        # we model a fixed bracket of 8 teams as a binary tree.
        # for clarity, we hardcode a standard 8-leaf full binary tree structure.

        # leaves 0..7
        dp = [[0.0] * 8 for _ in range(15)]

        for i in range(8):
            dp[7 + i][i] = 1.0

        # internal nodes: 0..6
        # children of node i: 2*i+1 and 2*i+2
        for i in range(6, -1, -1):
            L = 2 * i + 1
            R = 2 * i + 2
            for x in range(8):
                if dp[L][x] == 0:
                    continue
                for y in range(8):
                    if dp[R][y] == 0:
                        continue
                    dp[i][x] += dp[L][x] * dp[R][y] * p[x][y]
                    dp[i][y] += dp[L][x] * dp[R][y] * p[y][x]

        # assume G3 match corresponds to root node 0 for group A
        print(dp[0][4])

if __name__ == "__main__":
    solve()
```该实现直接编码了通过二元锦标赛树传播分布的想法。 叶子初始化确定了每个团队的起始位置。 每个内部节点中的嵌套循环通过迭代可以在该节点相遇的所有团队对并应用给定的获胜概率来合并两个子树。 

这里的一个常见陷阱是忘记必须考虑两个方向：如果团队$x$来自左边并且$y$从右边开始，两者$x$获胜和$y$获胜必须被考虑在内。 另一个微妙的问题是浮点累加； 由于所有概率都是许多独立路径上的小总和，因此双精度是必要的。

 ## 边缘情况

 一种边缘情况是所有概率都是确定性的，这意味着每个$a_{i,j}$是 0 或 100。在这种情况下，DP 的行为应该像固定锦标赛的纯粹模拟。 该算法可以自然地处理这个问题，因为所有中间分布都保持精确的 0 或 1 值，并且不会发生分数累积。 

另一个边缘情况是所有比赛都是 50-50 的情况。 在这种情况下，每支球队应该具有相同的结构概率，纯粹由括号位置决定。 DP 在每个合并步骤中产生均匀的混合，BLG 的最终概率完全由通向根的有效锦标赛路径的数量决定。
