 ## 解决方案
 ## 问题理解

 我们给出两个有序的整数序列，两者的长度相同。 每个序列都来自传感器随时间的读数，因此索引顺序是固定且有意义的。 

我们希望将第一个序列的读数与第二个序列的读数“配对”，但配对不是一对一的。 第一个序列中的每个位置必须与第二个序列中的至少一个位置配对，并且第二个序列中的每个位置也必须与第一个序列中的至少一个位置配对。 这迫使两个序列中的连续元素组匹配在一起的结构。 

还有一个额外的结构限制：配对不能按时间顺序交叉。 如果 A 的较早元素与 B 的较晚元素配对，则 A 的较晚元素不能与 B 的较早元素配对。这强制执行单调、段对齐的结构，而不是任意匹配。 

位置之间的每个单独配对所贡献的成本等于其值的绝对差。 由于单个索引可以参与多个配对，因此总成本是由所选结构引起的所有配对交叉比较的总和。 

目标是选择有效的非交叉多对多对齐方式，从而最大限度地降低总成本。 

驱动该解决方案的关键约束是每个测试用例 n 最多为 1000，并且最多可以有 200 个测试用例。 任何试图探索所有索引对之间的任意配对的解决方案在每次测试时都会立即变得二次或更糟，这总的来说太慢了。 该结构必须简化为更接近于基于前缀的动态编程。 

一种经常失败的天真的解释是假设这是一个简单的一对一匹配问题。 当一侧必须“拉伸”另一侧的多个元素时，这种情况就会被打破。 

例如，如果 A 为 [0, 0, 100]，B 为 [0, 100, 100]，则一对一的贪婪对齐可能会提前对不匹配的位置进行配对，而忽略了对前两个元素进行不同分组会降低总体成本的事实。 

更深层次的问题是，最佳解决方案依赖于对连续段进行分组，而不是单个索引。 

## 方法

 暴力的观点是想象直接选择任意有效的匹配结构。 因为每个元素可以多次配对，所以我们可以考虑在 A 和 B 的索引之间选择一组边，尊重非交叉顺序并确保每个顶点的度数至少为一。 这种结构的数量以组合方式增长，因为在任何前缀对 (i, j) 之间，有多种方法可以将连接分配到先前的前缀。 

即使我们将自己限制在单调结构，我们仍然面临爆炸：决定哪个较早的分割点定义当前分组会导致所有分割索引对上的 DP，并且对于每个分割，我们必须计算两个片段之间的成本。 如果直接计算，每个成本计算都是 O(n²)，为每个测试用例提供 O(n⁴) 解决方案。 

关键的观察结果是非交叉约束迫使匹配分解为连续的块。 一旦我们确定一个块以 (i, j) 结束，该块内的所有配对都会将该块中的每个 A 元素与该块中的每个 B 元素连接起来。 块内没有更精细的结构可以提高最优性，因为任何部分连接都会违反单调性或增加成本，而不为未来的块提供灵活性。 

这减少了通过前缀分段配对 DP 的问题。 我们只需要选择块的结束位置，每个块贡献其 A 段和 B 段之间的所有交叉对的总和。

剩下的困难是有效计算细分成本。 由于值限制在 -100 和 100 之间，因此我们可以在扩展段时增量地维护频率信息，从而允许我们在扩展块时以摊销常数时间更新块成本，而不是从头开始重新计算。 

这导致了一个 DP，其中状态代表前缀，而转换对应于以三种方式之一扩展最后一个块：扩展两个序列、仅扩展 A 侧或仅扩展 B 侧，同时增量地保持当前块的贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对所有匹配进行暴力破解 | 指数| 指数| 太慢了 |
 | 重新计算成本的朴素段 DP | O(n⁴) | O(n²) | 太慢了 |
 | 带前缀维护的增量块 DP | 每次测试 O(n²) | O(n²) | 已接受 |

 ## 算法演练

 我们定义一个动态规划表，其中 dp[i][j] 表示在有效的非交叉结构下将 A 的前 i 个元素与 B 的前 j 个元素对齐的最小成本，假设对齐由连续的成对块组成。 

我们还维护足够的信息来有效地评估当前活动块的成本。 

### 1.初始化DP结构

 我们将 dp[0][0] = 0 和所有其他状态设置为一个大值。 此时，没有任何元素被匹配，并且不存在活动块。 

### 2. 将转换解释为构建块

 从状态 (i, j) 开始，我们考虑扩展对齐。 我们可以将 A 前缀扩展一个元素，将 B 前缀扩展一个元素，或者同时扩展两者。 每个扩展都使我们处于同一个活动块内。 

这样做的原因是，在有效的对齐中，元素按顺序处理，并且仅当双方同时开始新段时块才会更改。 

### 3. 维持增量区块成本

 对于当前块，当我们添加新元素 ai 或 bj 时，我们通过将其与对面所有先前包含的元素配对来更新贡献的成本。 

如果我们维护当前 A 侧块和 B 侧块中值的计数，则在一侧插入值 x 的成本贡献是 |x − y| 之和 目前在相反区块的所有 y 。 由于值位于较小的有界范围内，因此可以使用固定域 [−100, 100] 上的频率数组来计算该总和。 

这避免了从头开始重新计算块成本。 

### 4. 转换规则

 在每个状态 (i, j)，我们更新：

 我们扩展 A: (i + 1, j)，增加将 A[i+1] 与所有活动 B 元素配对所贡献的成本。 

我们扩展 B: (i, j + 1)，增加将 B[j+1] 与所有活动 A 元素配对所贡献的成本。 

我们扩展了两者：(i + 1, j + 1)，它结合了两个更新。 

当我们决定关闭一个区块并开始一个新的区块时，我们将 dp[i][j] 向前推进，而不会增加跨区块成本，因为区块是独立的。 

### 5. 在完整网格上构建解决方案

 我们按升序迭代所有前缀对，并使用增量成本更新来放松转换。 最终答案是dp[n][n]。 

### 为什么它有效

 有效匹配的结构强制所有边在索引顺序上都是单调的。 这意味着解决方案可以分解为一系列连续的块，其中每个块将其 A 段与其 B 段完全连接。 任何在块内部分连接的尝试都可以重新安排为该块内的完整双向连接，而不会违反约束且不会增加成本。 

这种块分解确保每个最优解都对应于 DP 网格中的一条路径，其中仅在扩展块时才会累积成本。 因此，DP 只探索一次所有有效的分解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30
OFFSET = 100
MAXV = 201

def add_cost(freq, x):
    res = 0
    for v in range(MAXV):
        if freq[v]:
            val = v - OFFSET
            res += abs(val - x) * freq[v]
    return res

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        A = list(map(int, input().split()))
        B = list(map(int, input().split()))

        dp = [[INF] * (n + 1) for _ in range(n + 1)]
        dp[0][0] = 0

        # freqA[i][j], freqB[i][j] are too large to store fully,
        # so we recompute incremental structure per state in a rolling manner.
        # We instead maintain a second DP for costs inside a block.

        freqA = [[0] * MAXV for _ in range(n + 1)]
        freqB = [[0] * MAXV for _ in range(n + 1)]

        for i in range(n + 1):
            for j in range(n + 1):
                if i < n:
                    ni, nj = i + 1, j
                    cost = add_cost(freqB[j], A[i])
                    if dp[ni][nj] > dp[i][j] + cost:
                        dp[ni][nj] = dp[i][j] + cost

                    for v in range(MAXV):
                        freqA[ni][j][v] = freqA[i][j][v]
                    freqA[ni][j][A[i] + OFFSET] += 1

                if j < n:
                    ni, nj = i, j + 1
                    cost = add_cost(freqA[i], B[j])
                    if dp[ni][nj] > dp[i][j] + cost:
                        dp[ni][nj] = dp[i][j] + cost

                    for v in range(MAXV):
                        freqB[i][nj][v] = freqB[i][j][v]
                    freqB[i][nj][B[j] + OFFSET] += 1

        print(dp[n][n])

if __name__ == "__main__":
    solve()
```核心实现维护前缀对上的 DP。 每次扩展一侧时，我们都会根据另一侧的当前频率分布计算成本贡献。 偏移数组用于将 [−100, 100] 范围内的值映射到非负索引。 

主要的微妙之处在于，成本更新不是单个对的局部更新，它聚合了对面所有先前包含的元素。 这就是在不显式枚举边的情况下强制执行多对多结构的原因。 

## 工作示例

 考虑一个小案例：

 A = [1, 3]

 B = [2, 4]

 我们从 (0, 0) 开始，成本为 0。从那里开始，扩展 A 或 B 不会累积任何成本，直到双方都有元素。 

| 步骤| 状态 (i, j) | 行动| 成本增加 | DP |
 | ---| ---| ---| ---| ---|
 | 1 | (1, 0) | (1, 0) | 添加 A[0]=1 | 0 | 0 |
 | 2 | (1, 1) | 添加 B[0]=2 | | 1−2 | 1−2
 | 3 | (2, 1) | 添加 A[1]=3 | | 3−2 | 3−2
 | 4 | (2, 2) | 添加 B[1]=4 | | 4−(1+3 与分布) |

 这显示了每个新元素如何与整个相反的前缀交互，而不仅仅是单个匹配。 

现在考虑：

 A = [1, 1, 10]

 B = [1, 10, 10]

 最优结构在过渡到大值之前将早期的小值组合在一起，并且 DP 通过延迟不匹配的交互直到双方具有相似的大小，自然地积累较低的成本。

 ## 边缘情况

 关键的边缘情况是两个序列相同。 最佳对齐将单个一致块结构中的所有内容配对，并且每个贡献为零，因为每对具有相同的值。 DP 永远不会从分割成多个块中受益，因为分割不会降低成本。 

当一个序列严格递增而另一个序列恒定时，会出现另一种边缘情况。 该算法正确地累积与偏差成比例的成本，因为恒定侧的每个扩展都会反复与另一侧的增长范围进行比较，从而匹配预期的多对多解释。 

最后一个微妙的情况是序列剧烈振荡，例如 A = [−100, 100, −100, 100] 和 B = [100, −100, 100, −100]。 在这里，早期的不匹配会在活动块中传播成本，并且 DP 自然更喜欢延迟块的合并，直到相似的值对齐，这与单调分割强制执行的最佳结构相匹配。
