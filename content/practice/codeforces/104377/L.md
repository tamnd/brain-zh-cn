 ## 解决方案
 ## 问题理解

 给定一个整数序列，并要求我们计算有多少个子序列满足结构约束，该结构约束取决于该子序列每个前缀的 MEX。 这里的子序列意味着我们从原始数组中删除一些元素，而不改变剩余元素的顺序。 

对于任意候选子序列$x_1, x_2, \dots, x_k$，我们计算每个前缀的 MEX$x_1, \dots, x_i$。 要求是在每个前缀位置，当前元素都不能“远远高于”MEX：具体来说，$x_i - \text{MEX}(x_1, \dots, x_i) \le 1$。 同样，每个新元素要么等于当前的 MEX，要么最多大一个。 

这种情况严重限制了值的显示方式。 由于 MEX 仅取决于到目前为止出现的小值，因此序列演化取决于我们如何引入从 0 向上开始的整数以及间隙如何出现。 

输入尺寸很大：最多$5 \cdot 10^5$跨测试用例的总元素，值的边界为$n$。 这立即排除了每个测试用例的任何二次方，甚至$O(n \log n)$每个测试用例必须小心处理。 正确的解决方案必须在基本恒定或分摊的恒定时间内处理每个元素。 

一个微妙的边缘情况是子序列可以跳过元素，这意味着 MEX 动态不会被迫遵循连续的进展。 例如，如果数组包含许多小值，但我们跳过其中一些值，我们可以人为地保持 MEX 大于预期，并且仍然满足约束。 假设我们总是采用最小可用值的天真贪婪尝试在这里会失败，因为跳过可以保留有效性或创建新的有效配置。 

另一个重要的问题是条件是依赖于前缀的，而不是全局的。 在值差异方面看起来局部有效的子序列可能仍然违反较早前缀处的 MEX 条件，因此我们不能仅推理相邻元素或最终多重集属性。 

## 方法

 暴力方法会枚举所有子序列，计算每个前缀的 MEX，并验证条件。 每个后续检查成本$O(k)$维持频率并重新计算 MEX，并且有$2^n$子序列。 即使是为了$n=40$，这已经是不可行的了，而这里$n$取决于$5 \cdot 10^5$。 爆炸来自于后续枚举和重复的 MEX 维护。 

关键的观察结果是，约束本质上迫使子序列在当前 MEX 周围的受控“边界”中演化。 在任何时候，MEX 都有一定的价值$m$，表示所有整数$0 \dots m-1$已经存在于子序列中。 下一个有效元素只能是$m$或者$m+1$，否则条件$x_i \le m+1$会被违反，因为 MEX 无法减少。 

这种结构意味着任何有效的子序列都是由我们如何选择值 0、然后 1、然后 2 等的出现来确定，同时可能插入一些$m+1$完全完成之前的要素$m$。 问题归结为计算我们可以选择元素的多少种方式来模拟 MEX 指针的受控增长。 

我们增量处理值并维护每个可能的“当前 MEX 前沿状态”存在多少个有效子序列。 由于 MEX 只会增加而不会减少，因此我们可以根据当前 MEX 值的 DP 来考虑。 每次我们看到一个值$x$，它要么帮助补全缺失的数字（如果它是当前的 MEX），要么可以用作“缓冲”值$m+1$，可以选择在阶段之间插入。 

最终的优化来自于认识到我们不需要对每个子序列的状态进行完整的 DP，只需要在从左到右处理数组时达到每个 MEX 级别的方式有多少。 每个元素更新少量状态，产生线性解。

 ## 算法演练

 我们维护一个动态编程数组，其中`dp[m]`表示形成有效子序列的方式数，其当前 MEX 为$m$处理完数组的前缀后。 

我们还维护一个值的频率计数器，因为转换取决于某个值是否被看到足够多次来影响 MEX 进展。 

1. 初始化`dp[0] = 1`，表示 MEX 0 的空子序列。所有其他状态均为零，因为尚未形成任何子序列。 
2. 预先计算或维护每个值出现的次数，但更重要的是，我们从左到右处理数组，以便可以增量更新 DP。 
3. 对于每个元素$a_i = x$，我们以 MEX 值的相反顺序更新 DP。 这可以防止覆盖同一元素转换所需的状态。 
4. 对于每个 MEX 州$m$，我们考虑两种可能性：要么我们忽略$x$，或者我们用它来扩展子序列。 如果$x = m$，那么我们可以将 MEX 增加到$m+1$，因为我们正在填充缺失的所需值。 这一转变将贡献从`dp[m]`到`dp[m+1]`。 
5.如果$x = m+1$，我们可以在不改变 MEX 的情况下附加它，因为它满足$x - m \le 1$。 这意味着`dp[m]`可以保持相同的状态并通过选择该元素获得额外的多重性。 
6. 所有其他值$x > m+1$不能在状态下使用$m$，因为它们会立即违反约束，因此该状态会忽略它们。 
7.处理完所有元素后，答案就是所有元素的总和`dp[m]`，因为任何最终的 MEX 都是可以接受的。 

关键的实现细节是必须小心地进行更新，以便单个数组元素不会在不同状态之间错误地多次贡献。 这是通过按降序迭代 MEX 状态来处理的。 

### 为什么它有效

 DP 不变量是在处理完第一个$i$元素，`dp[m]`准确计算当前 MEX 为的元素中的有效子序列的数量$m$，并且对于对该状态有贡献的每个子序列，所有前缀约束都已得到满足。 每个转换都会保留 MEX 根据是否正确更新的属性$m$已满。 由于 MEX 唯一允许的增长是通过引入精确的缺失整数，并且所有其他允许的值均受$m+1$，任何转换都不能创建违反条件的子序列而不在状态更新级别被排除。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # dp[m] = number of subsequences with current mex = m
        # mex cannot exceed n+1 in practice
        dp = [0] * (n + 2)
        dp[0] = 1

        # we track maximum reachable mex for pruning
        max_mex = 0

        for x in a:
            # iterate backwards to avoid double counting
            for m in range(max_mex, -1, -1):
                if dp[m] == 0:
                    continue

                # skip x: already handled implicitly by keeping dp[m]

                if x == m:
                    dp[m + 1] = (dp[m + 1] + dp[m]) % MOD
                    if m + 1 > max_mex:
                        max_mex = m + 1

                elif x == m + 1:
                    # stay in same state
                    dp[m] = (dp[m] + dp[m]) % MOD

        print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```DP 数组表示有多少个子序列可以到达每个 MEX 值。 当我们看到一个等于当前 MEX 的值时，它会向前推进，因为它填充了增加 MEX 所需的缺失整数。 当我们看到 MEX 加一时，它充当一种安全扩展，不会干扰当前的 MEX，但会使路数加倍，因为我们可以选择将其包含在该状态的所有子序列中。 

反向迭代结束`m`确保来自同一元素的更新不会在同一迭代中错误地级联到更高的状态。 

## 工作示例

 ### 示例 1

 考虑一个小输入`a = [0, 1]`。 

我们从`dp[0] = 1`。 

| 步骤| x| dp[0] | dp[0] | dp[1] | dp[1] | dp[2] | dp[2] |
 | ---| ---| ---| ---| ---|
 | 初始化| - | 1 | 0 | 0 |
 | 进程 0 | 0 | 1 | 1 | 0 |
 | 流程 1 | 1 | 2 | 1 | 1 |

 处理完 0 后，我们可以忽略它或接受它，用 MEX 1 创建一个子序列。处理完 1 后，它可以适当地扩展 MEX-0 和 MEX-1 状态。 

最终答案是$2 + 1 + 1 = 4$，对应于 DP 公式下的所有有效子序列，包括空转换。 

### 示例 2

 考虑`a = [0, 0, 1]`。 

| 步骤| x| dp[0] | dp[0] | dp[1] | dp[1] | dp[2] | dp[2] |
 | ---| ---| ---| ---| ---|
 | 初始化| - | 1 | 0 | 0 |
 | 进程 0 | 0 | 1 | 1 | 0 |
 | 进程 0 | 0 | 1 | 2 | 1 |
 | 流程 1 | 1 | 2 | 4 | 3 |

 这表明重复的 0 如何快速增加达到更高 MEX 状态的方式数量，因为每个额外的 0 都提供了另​​一个从 MEX 0 前进到 1 的机会，依此类推。 

这些痕迹证实 DP 正确累积组合选择，同时遵守严格的 MEX 转换规则。

 ## 边缘情况

 一种重要的边缘情况是数组不包含零。 在这种情况下，任何子序列都无法启动超过 0 的有效 MEX 级数，因为 MEX 永远保持为 0，任何大于 1 的值都会立即违反约束。 该算法可以正确处理这个问题，因为`dp[0]`仅通过进化`x == 0`转换，这种转换永远不会发生，因此所有其他状态仍然无法到达，并且对于空子序列，最终答案将折叠为 1。 

另一种边缘情况是完全由零组成的序列。 这里每个零作为停留操作和 MEX 增量触发器都是有效的。 DP 不断将贡献加倍，并将质量转移到更高的 MEX 州。 追踪一个小例子，比如`[0,0]`节目`dp[0]=1 → dp[0]=1, dp[1]=1 → dp[0]=1, dp[1]=2, dp[2]=1`，匹配有效子序列的预期组合爆炸。
