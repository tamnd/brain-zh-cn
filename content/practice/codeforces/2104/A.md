 ## 解决方案
 ## 问题理解

 我们得到三叠卡片，排成一排，第一叠卡片包含`a`卡牌，第二张`b`卡，第三个`c`牌。 数满足`a < b < c`。 Monocarp 可以从第三堆中取出任意正数的牌，最多为所有`c`卡片，并在前两叠卡片之间重新分配它们。 目标是在重新分配后使所有三叠牌包含相同数量的牌。 

输入由多个测试用例组成，每个测试用例指定计数`a`,`b`， 和`c`。 如果可以进行均等分配，则每个测试用例的输出应为“是”，否则为“否”。 

因为每个`a`,`b`， 和`c`可以大到$10^8$并且最多可以有$10^4$测试用例，我们需要一个在每个测试用例恒定时间内工作的解决方案。 迭代第三层所有可能的重新分配会太慢，可能会执行到$10^8$每个案例的迭代次数。 

一个幼稚的实现可能会尝试从第三副牌移动到前两副牌的所有可能数量的牌，但这会超时。 另一个微妙的陷阱是无法检查牌的总数是否可以被三整除。 例如，如果`a=3, b=5, c=10`，总数为 18，除以 3，可以达到`6`每叠中的卡片。 如果总数为 19，则无法进行重新分配。 

## 方法

 暴力方法将涉及采取`x`第三副牌中的牌，分发`y`到第一层甲板并`x-y`到第二层甲板，并检查是否`a+y = b+x-y = c-x`。 对于每一个可能的`x`介于 1 和`c`，以及每个`y`0 到`x`，这需要最多$O(c^2)$检查。 这在理论上是正确的，但是最大可能的`c`是$10^8$，使得该方法不可行。 

关键的观察是每副牌中的最终值，我们称之为`target`，必须相同。 重新分配后的牌总数不变：`a + b + c`。 如果所有三副牌最终都相等，则该数字必须能被三整除。 所以`target = (a + b + c) / 3`。 如果`(a + b + c)`不能被3整除，这是不可能的。 

一旦我们知道`target`，我们只需要检查目标和前两副牌之间的差异最多为`c`，因为第三副牌可以提供那么多牌。 更正式地说，我们需要`(target - a) + (target - b) = 2*target - (a+b) = target - c`，这正是我们从第三副牌中取出的牌的数量。 自从`target <= c`（因为`c`是最大的），这有效。 否则的话，那是不可能的。 

这种观察将问题简化为简单的算术检查，并且每个测试用例的工作时间恒定。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(c²) | O(1) | O(1) | 太慢了|
 | 最佳| 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，读取值`a`,`b`， 和`c`。 
2. 计算所有三副牌的牌总数：`total = a + b + c`。 
3. 检查是否`total`能被3整除。如果不能，则输出“NO”并移至下一个测试用例。 这是因为平均分配需要将总数平均分配到三副牌中。 
4. 计算每副牌的目标牌数：`target = total // 3`。 
5. 检查是否最大的甲板，`c`, 至少包含`target`牌。 因为我们只能从`c`， 如果`target > c`，获得相同的牌组是不可能的。 在这种情况下输出“NO”。 
6. 否则，输出“YES”。 重新分配总是可以分配`target - a`将牌放入第一副牌并`target - b`将牌放到第二副牌上，准确拿取`(target - a) + (target - b)`来自第三副牌的牌。 

为什么它有效：不变的是我们必须达到`target`每副牌中的卡片。 总和可除性确保`target`是一个整数。 支票`target <= c`确保第三副牌有足够的牌来供应前两副牌。 这种逻辑保证了正确性，而无需模拟每种可能的重新分配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, c = map(int, input().split())
    total = a + b + c
    if total % 3 != 0:
        print("NO")
        continue
    target = total // 3
    if target > c:
        print("NO")
    else:
        print("YES")
```代码首先读取测试用例的数量。 对于每种情况，它都会计算三副牌的总和。 如果总和不能被三整除，则打印“NO”。 否则，它会计算目标牌组大小并检查最大的牌组是否可以提供所需的牌。 该实现使用整数除法和简单比较，这避免了浮点错误的风险。 该解决方案处理边缘情况，其中所需的重新分配的卡片数量可能为零。

 ## 边缘情况

 如果总和`a + b + c`能被 3 整除，但第三​​副牌没有足够的牌，算法正确输出“NO”。 例如，`a=1, b=2, c=2`有`total=5`，能被3整除吗？ 否，因此输出为“NO”。 为了`a=1, b=2, c=4`,`total=7`，不能被 3 整除，再次“NO”。 这些情况确保我们正确处理可分性和充分性条件。 最大的甲板总是`c`由输入约束保证，因此我们不需要检查其他排列。
