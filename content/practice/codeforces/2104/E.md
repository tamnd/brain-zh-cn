 ## 解决方案
 ## 问题理解

 我们有一个固定的参考字符串`s`，并且我们只能使用第一个`k`小写字母。 从这个字符串`s`，我们考虑任何字符串`t`如果它可以通过删除字符来形成，则为“有效”`s`不改变顺序，意思是`t`是一个子序列`s`。 

对于每个查询字符串`t`，我们可以在其右侧逐一附加字符，但仍限于相同的字符`k`字母。 每次追加后，我们检查结果字符串是否仍然是`s`。 任务是找到所需附加字符的最少数量，以便无论我们如何继续，结果字符串都不再是`s`。 

主要困难在于子序列匹配是全局的并且依赖于位置。 天真的尝试可能会模拟匹配`t`里面`s`，然后尝试所有可能的扩展，但这很快就变得不可行，因为两者`n`总查询长度可达百万左右。 

这些约束立即排除了任何基于查询的线性扫描`s`。 单个子序列检查是`O(n)`，并且为每个扩展或每个查询执行此操作将超出时间限制。 我们需要预处理`s`允许快速状态转换。 

当发生微妙的边缘情况时`t`已经不是以下的子序列`s`。 在这种情况下，根本不需要扩展，因为它已经立即“失败”了。 另一个极端情况是当`t`是一个子序列，但极其“接近”耗尽，这意味着它只能扩展几次，然后就无法继续。 

例如，如果`s = "abacaba"`和`t = "cc"`， 然后`t`已经不是子序列，所以答案是`0`。 如果`t = "b"`，那么我们仍然可以通过多种方式匹配它，但最终我们会耗尽有效的延续路径。 

真正的挑战是在我们不可避免地破坏子序列可行性之前量化还剩下多少安全扩展。 

## 方法

 对于每个查询字符串，直接的暴力方法将`t`，模拟将其匹配为子序列`s`。 如果已经失败，则返回`0`。 否则，我们尝试一次追加一个字符，并且每次都重新检查新字符串是否仍然是`s`。 

这是正确的，但速度非常慢。 每个后续检查成本`O(n)`，在最坏的情况下，我们可能会为每个查询尝试许多扩展，从而导致`O(n * total_query_length)`的行为，远远超出了界限。 

关键的观察是子序列匹配不依赖于完整的前缀历史记录，仅依赖于当前位置`s`。 一旦我们知道在哪里`s`我们正在匹配之后`t`，唯一的问题是：从这个位置开始，我们还能贪婪地消耗多少个字符，才根本无法再前进。 

这表明预处理转换：对于中的每个位置`s`对于每个字符，计算该字符的下一次出现。 然后，匹配后`t`，我们可以跳过`s`高效地同时贪婪地模拟扩展。 每个附加字符对应于使用预先计算的下一个指针向前移动。 当不存在有效转换时，该过程停止。 

这将每个查询减少为两个阶段：首先模拟匹配`t`在`s`，然后重复遵循转换，直到失败。 既然每一步都在向前推进`s`，所有查询的总工作量呈线性关系`n`加上总查询长度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(q·n·L) | O(q·n·L) | O(1) | O(1) | 太慢了|
 | 下次出现 DP | O(n·k + 总 L) | O(n·k) | O(n·k) | 已接受 |

 ## 算法演练

 我们构造一个转换表`nxt[i][c]`， 在哪里`i`是一个位置`s`和`c`是一个字符，存储位于或之后的下一个索引`i`在哪里`c`出现，或`-1`如果它不存在。 

然后我们按如下方式处理每个查询：

 1. 初始化`pos = 0`，这意味着我们在第一个字符之前开始`s`。 
2. 对于每个字符`t`， 更新`pos = nxt[pos][c] + 1`。 如果在任何时候`nxt[pos][c] = -1`， 然后`t`不是子序列，所以答案是`0`。 这一步直接模拟了线性时间内的子序列匹配`|t|`。 
3.如果`t`是一个子序列，我们现在反复尝试附加字符。 我们维护一个当前指针`pos`在`s`。 
4. 对于每个附加字符，我们选择任何允许的字符`c`可以将比赛推进`s`， 意义`nxt[pos][c] != -1`。 
5. 如果当前不存在该字符`pos`，我们无法进一步延伸，所以我们停下来。 
6.每次成功的追加动作`pos`转发到`s`，然后我们计算我们成功执行了多少步。 

答案是到达没有字符导致下一次有效出现的位置之前成功扩展的次数。 

### 为什么它有效

 在任何时刻，确定字符串是否仍然是子序列所需的唯一信息是当前匹配位置`s`。 这`nxt`表对任何位置的所有未来可能性进行编码。 每个附加字符严格推进位置`s`，因此该过程形成单调遍历`s`。 一旦所有字符都导致`-1`，没有扩展可以保留子序列属性，因此该过程必须停止。 这保证了最优性，因为附加字符的任何替代序列仍然需要来自相同状态的有效转换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())
    s = input().strip()

    # build next occurrence table
    nxt = [[-1] * k for _ in range(n + 1)]

    last = [-1] * k
    for i in range(n - 1, -1, -1):
        last[ord(s[i]) - 97] = i
        for c in range(k):
            nxt[i][c] = last[c]
    for c in range(k):
        nxt[n][c] = -1

    q = int(input())
    out = []

    for _ in range(q):
        t = input().strip()

        pos = 0
        ok = True

        for ch in t:
            c = ord(ch) - 97
            if pos > n:
                ok = False
                break
            nxt_pos = nxt[pos][c]
            if nxt_pos == -1:
                ok = False
                break
            pos = nxt_pos + 1

        if not ok:
            out.append("0")
            continue

        # try to extend
        ans = 0
        while True:
            found = False
            for c in range(k):
                nxt_pos = nxt[pos][c]
                if nxt_pos != -1:
                    pos = nxt_pos + 1
                    ans += 1
                    found = True
                    break
            if not found:
                break

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```预处理步骤构建一个表，允许直接跳转到下一个出现的任何字符。 这避免了向前扫描`s`在查询期间。 

子序列检查使用此表来更新`pos`高效。 如果无法匹配某个字符，则立即将查询解析为`0`。 

扩展阶段重复查找仍然可以使指针前进的任何字符。 有效字符的选择不会影响正确性，因为我们只计算可以继续的时间，而不是形成哪个确切的字符串。

 ### 示例 1

 输入：```

 | 3 | 乙| 3 | 4 | 5 |

 现在`t`是一个子序列，所以我们尝试扩展：

 | 延伸 | 邮政 | 选择的字符 | nxt[位置][c] | 新职位| 回答 |
 | --- | --- | --- | --- | --- | --- |

 | 停止| 7 | 无 | - | - | 2 |

这证实了在耗尽所有延续路径之前我们仍然可以将子序列扩展两次。 

### 示例 2

 输入：```

```匹配立即失败，因为第一个`c`存在但第二个`c`第一次出现后就无法匹配。 

| 步骤| 字符| 之前的位置 | nxt[位置][c] | 结果|

 由于子序列属性已经失败，答案是`0`。 无需延期。

 ## 边缘情况

 一种重要的边缘情况是查询字符串已经不可能作为子序列。 例如，如果`s = "abc"`和`t = "ddd"`，算法在第一个字符检查期间失败并返回`0`立即地。 这`nxt`表返回`-1`对于每一个`d`，因此不可能进行任何转换。 

另一种情况是当`t`比赛`s`完全着陆，到达终点位置`pos = n`。 在这种状态下，每次尝试扩展都会立即失败，因为`nxt[n][c] = -1`对于所有角色。 算法正确返回`0`，因为字符串已经最大限度地“不可扩展”。 

另一个微妙的情况是多个字符可用于扩展。 对第一个有效字符的贪婪选择是安全的，因为所有有效的转换都会前进`pos`，并且我们只计算任何有效路径存在的时间。 的结构`nxt`确保如果任何扩展都是可能的，则至少检测到一次向前移动，一旦不存在，则该过程确定性地停止。
