 ## 解决方案
 ## 问题理解

 我们得到了一个整数数组，并且允许我们使用非常特定的资源系统来修改它。 任何元素的每次增量都会花费一枚硬币，任何元素的每次减量都会花费一枚硬币。 我们从零硬币开始，因此任何操作序列都必须平衡，这样我们的硬币数量就不会出现负数。 

目标不是直接构造一个目标数组，而是决定我们应该保留哪些元素，以便剩余元素可以转换为称为理想的特殊配置。 理想数组有两个属性：每个值至少为 2，并且任意两个不同的元素互质。 

我们也可以在进行任何转换之前删除元素，并且我们希望删除尽可能少的元素，以便剩余元素可以在硬币规则下转换为某种理想的配置。 

硬币系统很重要，因为它有效地允许我们在元素之间重新分配价值而不改变总和。 任何增量都必须由其他地方先前或同时的减量提供资金，因此数组的总和在转换期间保持不变。 

这将问题转化为选择一个子集，该子集可以转换为至少为 2 的成对互质整数，同时保持总和不变。 

当数组大小较小时，会出现微妙的边缘情况。 如果我们只保留一个元素，则 gcd 条件空洞地为真，因此任何单个值只要能够达到至少 2，就总是可以成为理想值，这总是可能的，因为我们从已经至少为 2 的值开始。这使得单元素子集始终有效，这通常会破坏试图过于积极地强制执行成对约束的天真的推理。 

如果假设我们必须构造一个固定目标（例如素数或连续整数），则会出现另一种失败模式。 例如，认为所有保留的数字必须成为不同的素数的想法过于严格，并且会错过有效的转换，例如将许多值转换为相同的无复合结构，例如大于 2 的连续整数。 

真正的困难是确定在硬币守恒变换下实际上可以实现什么结构。 

## 方法

 蛮力的想法是尝试数组的每个子集。 对于每个子集，我们检查它是否可以转换为理想数组。 这意味着我们需要确定是否存在值的分配，所有值至少为 2 并且成对互质，以便总和与子集的当前总和相匹配。 由于我们可以使用硬币机制自由地移动价值，因此唯一的限制是是否存在具有相同大小和总和的目标多重集。 

即使我们简化并假设我们可以贪婪地赋值，子集的数量也是指数级的，因此这种方法在 n 达到 4e5 时立即失败。 

关键的观察结果是 gcd 约束极其严格。 如果我们希望所有选定数字中成对的 gcd 等于 1，那么特别是没有素数可以整除两个不同的选定数字。 这意味着每个质因子最多可以出现在最终子集中的一个元素中。 

这导致了结构上的重新表述：每个选定的数字必须“声明”一些素数，并且没有两个数字可以共享任何素数因子。 由于我们可以在保留总和的同时自由地变换值，因此原始值的实际数字身份仅通过我们可以“负担得起”唯一分配的小素数来影响。 

标准技巧是要注意，如果我们有足够的灵活性，则每个至少为 2 的数字都可以转换为不同素数的乘积，并且只要保留总和，硬币系统就允许价值的重新分配。 限制我们的不是大小，而是不同的主要“插槽”的可用性。

因此，问题简化为选择最大数量的元素，以便我们可以为每个元素分配不同的素数表示，并确保总和的可行性。 

由于素数不断增长，最佳打包策略是将尽可能小的不同素数分配给尽可能多的元素。 最小的素数是 2、3、5、7、11 等。 分配 k 个最小素数的成本大约是它们的总和，我们将其与所选元素的可用总和进行比较。 

因此问题就变成了：选择最大的 k 使得 k 个最小素数的和至多是所选子集的和，并且 k 也受到子集大小的限制。 

我们对数组进行排序，计算前缀和，并通过从最大子集向下检查可行性来贪婪地尝试保留尽可能多的元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集的暴力破解 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 带有前缀 + 素数的贪心 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 将数组按降序排序，以便我们首先考虑保留较大的值。 这有助于最大化分配素数结构的可用总和。 
2. 计算排序数组的前缀和。 如果我们保留前 k 个元素，每个前缀代表总“预算”。 
3. 预先计算前 n 个素数及其前缀和的列表。 这表示分配 k 个不同互质时隙所需的最小成本。 
4. 对于从n到1的每个可能的k，检查最大的k个元素的和是否至少是前k个素数的和。 如果是，那么保留k个元素是可行的。 
5. 返回 k 的最大值，并输出 n 减去该值作为删除次数。 

我们与素数前缀和进行比较的原因是，任何有效的 k 个成对互素数的构造都需要至少 k 个不同的素数“单位”，而实现 k 个这样的单位的最便宜的方法是使用最小的素数。 

### 为什么它有效

 不变的是，任何大小为 k 的理想配置都必须编码 k 个不相交的素数因子集合，并且每个这样的集合具有由至少一个不同素数确定的最小可能“成本”。 由于素数是 gcd 结构的不可约构建块，因此当我们分配最小的可用素数时，就实现了最小的总要求。 硬币操作允许任意重新分配价值，但保留总金额，因此可行性降低为与此最低主要成本概况的纯粹预算比较。 这确保了如果贪婪条件对于 k 成立，则存在有效的变换，并且如果失败，则任何值的重新排列都无法补偿总和不足。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def sieve_primes(n):
    limit = 200000  # enough for prefix sizes up to 2e5
    is_prime = [True] * (limit + 1)
    is_prime[0] = is_prime[1] = False
    primes = []
    for i in range(2, limit + 1):
        if is_prime[i]:
            primes.append(i)
            if len(primes) >= n:
                break
            for j in range(i * i, limit + 1, i):
                if j <= limit:
                    is_prime[j] = False
    return primes

t = int(input())
max_n = 0
tests = []
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    tests.append((n, a))
    max_n = max(max_n, n)

primes = sieve_primes(max_n)
prime_ps = [0]
for p in primes:
    prime_ps.append(prime_ps[-1] + p)

out = []

for n, a in tests:
    a.sort(reverse=True)
    pref = [0]
    for x in a:
        pref.append(pref[-1] + x)

    ans = 0
    for k in range(1, n + 1):
        if pref[k] >= prime_ps[k]:
            ans = k
    out.append(str(n - ans))

print("\n".join(out))
```该代码首先对每个数组进行排序，以便将大小为 k 的任何候选子集假定为 k 个最大元素，因为这样可以最大化可用总和。 前缀总和数组让我们可以在常数时间内计算总数。 

然后，我们将其与最小素数的前缀和进行比较，这是构造 k 成对互素数的最低要求。 循环找到最大的可行k，答案是必须删除多少个元素。 

一个常见的陷阱是忘记我们不是在数组内构建实际的素数； 我们仅使用素数作为 gcd 分离要求的下界模型。

 ## 边缘情况

 一种边缘情况是所有元素都相同且很小，例如许多 2。 在这种情况下，虽然值单独有效，但 gcd 条件阻止任何对在理想数组中共存。 该算法反映了这一点，因为素数的前缀和很快超出了每个附加元素的可用预算，迫使解决方案放弃几乎所有内容。 

另一种边缘情况是数组包含单个元素时。 由于 gcd 约束对于大小 1 消失，因此该算法始终允许 k = 1，因此不需要删除。 前缀比较自然会通过，因为任何至少 2 的值都会超过第一个素数的成本。 

第三种情况是值很大但很少。 即使数字很大，限制也是结构性的，而不是数字上的； 主要成本增长最终占主导地位，因此大值仅在它们增加总和足以支持更多元素时才有帮助，而不是因为它们直接改变 gcd 属性。
