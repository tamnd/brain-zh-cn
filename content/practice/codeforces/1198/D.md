 ## 解决方案
 ## 问题理解

 我们得到一个二进制网格，其中一些单元格是黑色的，其余的单元格已经是白色的。 我们唯一的操作是选择任何轴对齐的矩形并将其中的每个单元格重新绘制为白色。 每个此类操作的成本等于其高度或宽度中的较大者。 目标是删除所有黑色单元，同时最小化所有选定矩形的总成本。 

这个问题之所以微妙，是因为矩形可以任意重叠，多次重新绘制单元格是无害的，但每次选择矩形时仍然要花钱。 因此，真正的决定不是覆盖单元格一次，而是如何以经济高效的方式将黑色单元格划分为矩形。 

网格大小最多为 50 x 50，这已经表明二次或三次动态规划解决方案是合理的。 单元子集上的任何指数都立即无法实现，但子矩形上的区间式 DP 是可行的，因为可能的矩形数量约为 \(O(n^4)\)，该数量足够小，可以通过额外的分割逻辑进行管理。 

一些边缘情况很容易被低估。 如果网格已经没有黑色单元格，则答案必须为零，因为不需要任何操作。 如果黑色单元格形成一个完整的矩形，那么答案就是该矩形的成本，因为绘制一次是最佳的。 更具欺骗性的情况是黑色单元格形成断开的图案：例如，两个遥远的单个单元格。 一种天真的方法可能会尝试用一个大矩形覆盖它们，但这可能比单独处理它们更糟糕，因为成本取决于 max(height, width)，而不是面积。 

另一种失败模式来自于假设贪婪地扩展矩形总是有帮助的。 包含许多白色单元格的矩形仍然是允许的，但即使没有增加任何好处，它也会增加成本，因此最佳策略必须仔细决定合并区域是否值得。 

## 方法

 蛮力视角是考虑用矩形覆盖黑色单元的所有可能方法，计算每种配置的成本，并取最小值。 即使我们限制自己只考虑紧密束缚黑色单元子集的“​​有用”矩形，子集的数量也是指数级的，并且每个子集可以对应于许多矩形分区。 即使对于\(n = 10\)，因为将网格中的一组点划分为矩形的方法数量增长得非常快。 

关键的结构观察是，任何最佳解决方案都可以通过将黑色单元包围在边界矩形中并将剩余区域分割成更小的子问题来递归分解。 如果我们采用包含一组黑色单元格的最小矩形，我们可以直接为该矩形付费，也可以选择沿某些行或列分割它，独立地求解两个结果子矩形。 这将问题转化为子网格上的经典区间 DP。 

这样做的原因是成本函数仅取决于矩形尺寸，而不取决于黑色单元的内部排列。 这使得每个子矩形都是一个独立的决策单元：一旦我们修复了一个矩形，它之外发生的事情就是独立的。 

我们为每个子矩形 \((x_1, y_1, x_2, y_2)\) 定义一个 DP 状态，表示清除其中所有黑色单元的最小成本。 对于每种状态，我们计算两种类型的答案：要么在一次操作中清除整个边界矩形，要么水平或垂直分割它并组合解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 | 指数| 指数| 太慢了 |
 | 间隔 DP | \(O(n^5)\) | \(O(n^4)\) | 已接受 |

 ## 算法演练

 我们将每个子矩形视为一个状态，并按面积递增的顺序计算答案，以便在需要时已经解决了较小的矩形。 

1.我们定义一个DP表，其中`dp[x1][y1][x2][y2]`存储清除该子矩形中所有黑色单元格的最小成本。 这直接编码了每个可能区域上的决策问题。 

2. 对于每个矩形，我们首先检查它是否包含黑色单元格。 如果没有，其成本为零。 这避免了不必要的工作并确保空白区域不会做出贡献。 

3. 如果矩形非空，我们将其成本初始化为`max(height, width)`，相当于在一次操作中绘制整个矩形。 这代表了最简单的有效策略。 

4. 然后，我们尝试在每个可能的行处水平分割矩形。 每次分割都会将该区域划分为两个独立的子问题，其成本会增加。 我们用最佳的分割来更新 DP 值，因为任何不能一次性覆盖整个矩形的最佳解决方案都必须遵守操作之间的某种水平间隔。 

5. 我们对垂直分割重复相同的想法，再次组合左右子问题。 这确保我们探索该区域的所有轴对齐分解。 

6.最终答案是`dp[1][1][n][n]`，因为它代表清理整个网格的成本。 

基本思想是，每个最佳解决方案要么使用完整的矩形操作，要么可以沿着将其绘制的结构分成独立部分的切割进行分解。 

### 为什么它有效

 正确性来自于以下事实：任何矩形绘制操作序列都会将网格划分为受每个操作影响的最大区域。 对于任何此类解决方案，请考虑在分裂发生之前一起处理的单元格的边界框。 该解决方案要么直接绘制整个边界框，要么执行剪切，将操作分成不相交的子矩形。 由于成本在操作上是累加性的并且在不相交区域之间是独立的，因此 DP 递归精确地探索了所有可能的结构分解。 没有最佳解决方案可以避免被表示为此类分割的序列，因为任何基于矩形的操作序列都可以沿着其第一个分离切割递归地分解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
grid = [input().strip() for _ in range(n)]

pref = [[0]*(n+1) for _ in range(n+1)]

for i in range(n):
    for j in range(n):
        pref[i+1][j+1] = (
            pref[i][j+1]
            + pref[i+1][j]
            - pref[i][j]
            + (1 if grid[i][j] == '#' else 0)
        )

def has_black(x1, y1, x2, y2):
    return (
        pref[x2][y2]
        - pref[x1][y2]
        - pref[x2][y1]
        + pref[x1][y1]
    ) > 0

dp = [[[ [0]*n for _ in range(n)] for _ in range(n)] for _ in range(n)]

for h in range(1, n+1):
    for w in range(1, n+1):
        for x1 in range(n - h + 1):
            x2 = x1 + h
            for y1 in range(n - w + 1):
                y2 = y1 + w

                if not has_black(x1, y1, x2, y2):
                    dp[x1][y1][x2][y2] = 0
                    continue

                best = max(h, w)

                for k in range(x1 + 1, x2):
                    best = min(best,
                               dp[x1][y1][k][y2] + dp[k][y1][x2][y2])

                for k in range(y1 + 1, y2):
                    best = min(best,
                               dp[x1][y1][x2][k] + dp[x1][k][x2][y2])

                dp[x1][y1][x2][y2] = best

print(dp[0][0][n][n])
```该实现依靠 3D 前缀和来快速检查子矩形是否包含任何黑色单元。 这是至关重要的，因为否则每个 DP 转换都需要扫描矩形，从而不必要地增加复杂性。 

DP 表通过子矩形的坐标进行索引，并且我们通过增加大小进行迭代，以便每个分割仅引用已经计算的较小矩形。 初始值`max(h, w)`编码一次绘制整个区域的成本，并且所有分割过渡都试图对其进行改进。 

必须注意坐标边界：DP 使用半开区间`[x1, x2)`和`[y1, y2)`，这避免了分割过程中的逐一混淆。

 ## 边缘情况

 完全空的网格会触发 DP 基本情况，其中每个矩形的成本为零。 该算法通过前缀和来检查这一点，因此每个子矩形立即被分配为零，从而防止不必要的递归或更新。 

大网格内的单个黑色单元迫使算法比较两种策略：支付大矩形或递归分裂直到单元被隔离。 DP 正确地更喜欢单细胞矩形，因为`max(1,1) = 1`主导任何分裂。 

黑色单元的水平或垂直细条确保沿正交轴的分割变得最佳。 该算法可以处理这一问题，因为一个方向始终产生零成本子矩形，而另一个方向则累积最小矩形成本，从而正确引导 DP 进行线对齐分解。
