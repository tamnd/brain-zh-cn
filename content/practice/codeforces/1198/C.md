 ## 解决方案
 ## 问题理解

 我们给出了几个无向图，每个图都精确地$3n$顶点。 对于每个图，我们必须构造两个特定大小的结构之一$n$: 要么是由以下组成的匹配$n$边，或由以下组成的独立集合$n$顶点。 如果这两种结构都不存在，我们必须报告不可能性。 

匹配是一组边，其中没有顶点出现在多个选定的边中。 独立集是一组顶点，图中没有边连接任何一对选定的顶点。 

关键困难在于图很大并且稀疏约束得不到保证：$n$可以达到$10^5$每个测试用例，总边数可达$5 \cdot 10^5$。 这立即排除了任何试图枚举顶点或边的子集的方法，甚至排除了任何二次的方法$n$。 每个测试用例的解决方案必须基本上是线性或线性对数的。 

当两种结构都存在时，就会出现微妙的边缘情况。 例如，在一个图中，顶点形成许多不相交的边加上孤立的节点，既可以是匹配的，也可以是独立的大小集$n$是可能的。 该问题允许任一答案，因此任何确定性选择策略都是可以接受的。 

另一个重要的边缘情况是当图非常密集时。 如果边缘丰富，则可能很容易找到匹配，但独立集会变小。 相反，如果边缘非常稀疏，独立集会变大，但匹配结构可能会失败。 解决方案不得采用任何一种制度。 

第三种不明显的情况是当图形被结构化时，大小既不能完全匹配$n$也不是一组独立的尺寸$n$存在。 官方解决方案中的构造确保这种情况除了简单的矛盾检查之外永远不需要复杂的后备逻辑。 

## 方法

 直接的暴力破解思想是尝试独立构造最大匹配集和最大独立集。 人们可以运行贪婪匹配，并根据补集计算贪婪独立集，或者尝试通过 DP 或基于流的归约来计算最大独立集。 这些方法要么是指数方法，要么需要解决 NP 难子问题，这在以下情况下是不可行的：$n = 10^5$。 

关键的结构见解是该图具有$3n$顶点，但我们只需要一个大小的结构$n$，这正好是顶点集的三分之一。 这种不平衡至关重要。 它表明，如果我们找不到足够的不相交边，那么许多顶点必须在强意义上保持“不匹配”，并且可以将这些顶点组织成一个独立的集合。 

标准的建设性想法是贪婪地尝试匹配。 如果我们可以选择$n$不相交的边，我们就完成了。 如果我们失败了，失败意味着太多的顶点被之前的选择“阻挡”，这迫使一个大的独立集合存在。 该算法仔细跟踪使用的顶点并一次提取任一结构。 

更深入的观点是，我们选择的每条边都会减少可用的顶点，并且每次我们未能选择匹配的边时，我们都会在补图中获得有助于独立集的结构。

 ## 算法演练

 该解决方案是围绕维护一个简单的贪婪过程而构建的，该过程同时尝试构建匹配，同时隐式准备一个独立的后备集。 

我们维护未使用的顶点列表和已访问的数组。 我们还维护邻接表。 

### 1. 贪婪地尝试构建匹配

 我们按输入顺序迭代边。 对于每条边$(u, v)$，如果两个端点当前均未使用，我们会将这条边纳入匹配中，并将两个顶点标记为已使用。 我们继续直到我们收集$n$边缘或完成所有边缘。 

这是有效的，因为任何有效的匹配只需要不相交的端点，并且贪婪地挑选早期边缘可以避免以后不必要的冲突。 

### 2.如果匹配成功

 如果我们能够选择$n$边缘，我们立即输出它们。 这满足了要求。 

### 3.如果匹配失败

 如果我们无法到达$n$边，则少于$n$图中存在不相交的边。 这意味着至少$3n - 2(n-1)$顶点仍然没有通过我们的贪婪过程完全配对，这保证了足够的结构来形成一个独立的集合。 

我们通过获取匹配过程中从未使用过的所有顶点来构造一个独立的集合。 由于每个选定的边消耗两个顶点，因此剩余的集合至少包含$n$顶点。 然后我们取任何$n$其中。 

我们必须确保这个集合是独立的。 该剩余集合内的任何边都可用于更早的匹配（因为两个端点均未使用），这与贪婪匹配过程的最大值相矛盾。 

### 为什么它有效

 不变的是，贪婪匹配停止后，两个未使用的顶点之间不存在边。 如果存在这样的边缘，算法就会在处理该边缘时选择它。 因此，未使用的顶点集合在剩余图中形成独立的集合。 由于匹配未能达到尺寸$n$，未使用的集合必须至少包含$n$顶点，确保可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        adj = [[] for _ in range(3*n + 1)]
        edges = []

        for i in range(1, m + 1):
            u, v = map(int, input().split())
            adj[u].append((v, i))
            adj[v].append((u, i))
            edges.append((u, v))

        used = [False] * (3*n + 1)
        matching = []

        for i, (u, v) in enumerate(edges, 1):
            if not used[u] and not used[v]:
                used[u] = used[v] = True
                matching.append(i)
                if len(matching) == n:
                    break

        if len(matching) == n:
            print("Matching")
            print(*matching)
            continue

        indep = []
        for v in range(1, 3*n + 1):
            if len(indep) < n and not used[v]:
                indep.append(v)

        print("IndSet")
        print(*indep)

if __name__ == "__main__":
    solve()
```该代码首先构建邻接信息并按输入顺序存储边。 然后，它对边缘执行贪婪扫描，选择不相交的端点来构建匹配。 那一刻$n$边缘被收集，它输出它们。 

如果贪婪过程失败，它会收集未使用的顶点。 重要的细节是我们只需要取第一个$n$未使用的顶点，因为正确性保证至少有$n$其中。

 ## 边缘情况

 在没有边的图中，算法永远不会选择匹配的边，并以所有未使用的顶点结束。 然后构建只需第一个$n$顶点，它形成一个有效的独立集，因为独立性是通过没有边来保证的。 

在存在边但高度聚集在几个顶点周围的图中，贪婪匹配可能会提前停止。 例如，如果一个顶点连接到几乎所有其他顶点，则选择任何事件边会快速阻止涉及该顶点的未来匹配，但仍然留下大量未触及的顶点。 这些未触及的顶点形成有效的独立集，因为任何内部边都会更早地被选择为匹配候选者。 

在可以完美匹配的图中，贪婪选择可能会也可能不会找到完全匹配，具体取决于边顺序，但保证的是，如果没有找到，则保留足够的未使用顶点以形成独立的大小集$n$。 这是因为每次扩展匹配失败都对应于将质量转移到补集中的结构冗余。
