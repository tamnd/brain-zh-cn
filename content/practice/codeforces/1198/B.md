 ## 解决方案
 ## 问题理解

 我们正在维护一组固定公民的动态余额列表。 最初，每个公民都有已知数量的金钱。 然后一系列事件以两种不同的方式修改这些余额。 

第一种类型的事件直接将某个特定公民的余额设置为精确值，就好像收据覆盖了我们对该人当前资金的了解一样。 第二种类型的事件是全球政府行为：每个余额严格低于给定阈值的公民都会被提高到该阈值，而已经达到或高于该阈值的公民则保持不变。 

处理所有事件后的输出就是每个公民的最终余额。 

关键的困难在于，全局更新可能会同时影响许多公民，并且可能有多达 200,000 个事件。 在最坏的情况下，扫描所有公民的每次全局更新的简单方法将需要多达 400 亿次操作，这远远超出了 2 秒的限制所允许的范围。 这立即排除了每次更新时重新计算完整数组的任何解决方案。 

将个人更新和全局更新结合起来时会出现一个微妙的问题。 假设通过全局操作增加了一个公民，然后收到了直接更新。 如果我们不小心，我们可能会错误地“重新应用”旧的全局操作或用过时的值覆盖新的值。 例如，如果某个公民因全球事件而升至 10，后来又明确设置为 5，则仅跟踪最低阈值的简单实现会错误地将其恢复至 10。 

另一个边缘情况是阈值不断降低的重复全局操作。 除非我们明确处理每个位置更新的排序和持久性，否则关于最大阈值的天真的单调假设就会失败。 

## 方法

 暴力模拟将直接应用每个事件。 对于阈值 x 的 2 类事件，我们将扫描所有公民并更新值小于 x 的公民。 这是正确的，但代价高昂：每次这样的操作成本为 O(n)，当 q 达到 200,000 时，总成本变为 O(nq)，这太大了。 

关键的观察是全局更新只会提高值，并且它们基于阈值。 这表明，一旦公民的价值超过一定水平，就不再需要重新考虑更低的门槛。 然而，由于个人更新可能会降低公民的价值，因此我们不能简单地保持全局最大值。 

诀窍是向后处理事件。 如果我们反转时间线，类型 2 事件就会变成：“未来值必须至少为 x”，类型 1 事件就会变成已知的最终分配，可能会覆盖早期的约束。 逆向工作使我们能够为每个公民计算未来全局更新所施加的最佳可能下限，同时尊重最近的直接分配。 

为了准确起见，我们维护一个运行值`mx`表示迄今为止在逆向处理中看到的最大阈值。 当我们遇到全局更新时，我们更新`mx`。 当我们遇到公民 p 的个人分配时，如果该公民尚未最终确定，我们会分配给他们`max(a[p], mx)`。 

我们的见解是，一旦我们确定了公民的最终价值，早期的事件对他们来说就不再重要了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(n) | 太慢了 |
 | 使用最大跟踪进行逆向处理 | O(n + q) | O(n + q) | 已接受 |

 ## 算法演练

 我们以相反的顺序处理事件，以便全局约束成为累积的下限，而不是重复的数组扫描。 

1. 读取所有初始值并存储所有事件。 
2.初始化一个数组`ans`为每个公民“未分配”。 
3. 维护一个变量`mx = 0`，它反向存储迄今为止遇到的全局事件的最大阈值。 
4. 从最后一个到第一个迭代事件。 
5. 如果事件是有阈值的全局更新`x`， 放`mx = max(mx, x)`。 这表示我们以后决定的任何值都必须至少满足这个最低要求。 
6. 如果该活动是公民的个人更新`p`有价值`x`，并且该公民尚未分配，设置`ans[p] = max(x, mx)`。 这确保我们尊重直接分配和所有未来（按原始顺序）全局约束。 
7. 处理完所有事件后，任何仍未分配的公民都会收到`max(a[i], mx)`。 

这样做的原因是每个公民都被最终确定一次，此时我们第一次以相反的顺序遇到他们的最新任务。 此时，原始时间线中该分配之后发生的所有全局约束都已累积到`mx`。 

### 为什么它有效

 不变的是，当反向处理事件时，`mx`始终等于原始时间线中当前点之后发生的所有类型 2 操作的最大阈值。 因此，当我们最终确定公民的价值时，我们会在他们最后一次直接分配后正确执行影响他们的每一次全局更新。 由于我们只为每个公民分配一次，因此我们永远不会覆盖已经考虑了所有相关约束的值，并且未来的任何步骤都不会使其无效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
q = int(input())

events = []
for _ in range(q):
    parts = list(map(int, input().split()))
    events.append(parts)

ans = [-1] * n
mx = 0

for e in reversed(events):
    if e[0] == 2:
        mx = max(mx, e[1])
    else:
        _, p, x = e
        p -= 1
        if ans[p] == -1:
            ans[p] = max(x, mx)

for i in range(n):
    if ans[i] == -1:
        ans[i] = max(a[i], mx)

print(*ans)
```实现的核心是反向扫描。 我们不会模拟向前更新，因为这需要重复的完整扫描。 相反，我们将全局操作视为累积的持久约束`mx`。 

一个微妙的点是初始化`ans`与-1。 这确保了仅使用相反顺序的最新分配，这与在向前时间中，较晚的分配覆盖较早的分配这一事实相匹配。 

最后，初始数组仅用于从未收到直接分配事件的公民。 

## 工作示例

 ### 示例 1

 输入：```
4
1 2 3 4
3
2 3
1 2 2
2 1
```我们进行逆向处理。 

| 步骤| 活动 | MX | 分配的变更 |
 | ---| ---| ---| ---|
 | 1 | 2 1 | 2 1 | 无 |
 | 2 | 1 2 2 | 1 2 2 1 | ans[1] = 最大(2,1)=2 |
 | 3 | 2 3 | 3 | 无 |

 最终：

 - ans = [3,2,3,4]

 这显示了后来使用阈值 3 的全局更新如何支配早期较小的约束，以及如何根据累积约束限制直接分配。 

### 示例 2

 输入：```
5
3 50 2 1 10
3
2 0
1 2 0
2 8
```逆向处理：

 | 步骤| 活动 | MX | 行动|
 | ---| ---| ---| ---|
 | 1 | 2 8 | 8 | MX = 8 |
 | 2 | 1 2 0 | 1 2 0 8 | 答案[1] = 8 |
 | 3 | 2 0 | 2 8 | mx 保持 8 |

 最终：

 - ans = [8, 8, 8, 8, 10]

 这表明即使是低赋值 (0) 也会被后来的全局约束覆盖。

 ## 边缘情况

 一个重要的边缘情况是当一个公民被多次更新时，只有向前时间中最早的更新才应该作为最终状态。 在逆向处理中，这是自然处理的，因为我们分配`ans[p]`只有一次。 

考虑：```
3
1 1 1
3
1 1 5
1 1 2
2 10
```逆序：

 - 全局 10 组 mx = 10
 - 人员 1 遇到的第一个赋值设置 ans[0] = 10
 - 先前的分配被忽略

 算法正确返回：```
10 1 1
```另一个边缘情况是没有发生个人更新。 在这种情况下，所有值都会简单地提高到序列中任何位置可见的最大全局阈值。 自从`mx`聚合所有类型 2 事件，最终分配步骤正确地将其统一应用于所有公民。
