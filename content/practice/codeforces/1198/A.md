 ## 解决方案
 ## 问题理解

 我们得到了一系列声音强度，每个强度都是非负整数。 将其视为采样音频幅度的时间序列。 该文件使用每个值的固定位数进行存储，并且该位成本仅取决于我们可能修改数组后出现的不同值的数量。 

我们可以选择一个区间$[l, r]$。 该区间内的每个值都保持不变，所有较小的值都会被推到$l$，所有更大的东西都被推到$r$。 此操作减少了不同值的数量，因为所选窗口之外的所有内容都会折叠到其边界上。 

应用此转换后，存储成本取决于剩余的不同值的数量。 如果有$K$不同的价值，每个元素的成本$k = \lceil \log_2 K \rceil$位，因此总存储量为$n \cdot k$位。 磁盘容量以字节为单位，因此约束为$n \cdot k \le 8I$。 

任务是选择$[l, r]$以便转换后的数组适合磁盘，同时最大限度地减少转换期间更改的元素数量。 

这些限制迫使我们走向$O(n \log n)$或者$O(n)$解决方案。 和$n$最多$4 \cdot 10^5$，所有区间选择的二次方都是不可能的，因为有$O(n^2)$候选人$[l, r]$对。 甚至一个$O(n^2)$每个间隔持续工作的扫描将远远超出时间限制。 

当压缩要求无需任何更改就已得到满足时，就会出现微妙的边缘情况。 如果不同值的原始数量足够小，则最佳答案为零。 当所有值都相同时，会出现另一种边缘情况。 在这种情况下$K = 1$， 所以$k = 0$，意味着每个元素零位，并且文件适合任何磁盘，必须在计算对数或阈值的逻辑中仔细处理。 

天真的方法可能会尝试一切可能的方法$[l, r]$，压缩后重新计算不同的值，并计算移动的元素数量。 这会失败，因为重新计算压缩的不同值需要每次扫描数组，产生$O(n^3)$行为。 

## 方法

 蛮力策略在概念上很简单：固定一个间隔$[l, r]$，模拟压缩，计算有多少个元素位于间隔之外（这些是发生变化的元素），并计算钳位后剩余多少个不同的值。 然后验证生成的位数是否适合可用磁盘大小。 在所有有效间隔中，选择一个最小化更改元素数量的间隔。 

这是正确的，因为它直接评估操作的定义。 问题是性能：有$O(n^2)$间隔，并且每次模拟都是$O(n)$，导致$O(n^3)$最坏情况下的复杂性。 和$n = 4 \cdot 10^5$，这是完全不可行的。 

关键的观察是对数组进行排序后，选择$[l, r]$相当于在已排序的数组中选择一个保持不变的连续段。 该段之外的所有内容都被强制到边界，因此被视为修改。 因此，我们不是根据值来思考，而是根据排序列表中的索引来思考。 

然后我们重新解释存储的约束。 如果我们完全保留所选段内的不同值，加上可能的边界折叠，则我们需要的不同值的数量最多为$M = \left\lfloor \frac{8I}{n} \right\rfloor$当解释为位约束时$k$。 自从$k = \lceil \log_2 K \rceil$，这相当于有界$K$，问题就简化为在窗口内找到最大的相等值子集，该子集最多可以表示$K$独特的元素。 

排序后，最佳结构是不同值上的滑动窗口，最大化有多少数组元素落在最多一个段内$K$独特的价值观。 该窗口之外的所有内容都会发生变化，因此最小化更改相当于最大化保留的元素。 

因此，这个问题变成了一个关于排序数组计数的经典两指针问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$|$O(n)$| 太慢了 |
 | 最佳 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 对数组进行排序。 排序可确保将相等的值分组，这使我们能够使用连续的结构而不是分散的位置来推理不同的值。 
2. 按顺序计算每个不同值的频率。 这将问题从元素级移动减少到块级推理，因为所有相等的值在任何区间压缩下都表现相同。 
3. 计算允许的最大不同值数量$K_{\max}$使该文件适合磁盘。 这来自解决$n \cdot \lceil \log_2 K \rceil \le 8I$。 我们找到最大的$K$这样$\lceil \log_2 K \rceil$不超过每个元素的可用位数。 
4.如果$K_{\max}$至少是原始数组中不同值的数量，不需要压缩，所以答案为零。 
5. 否则，我们在不同值列表上维护一个滑动窗口。 每个窗口表示保持一组连续的值不变，而外部的所有值都被压缩到边界。 
6. 当我们扩展窗口的右边界时，我们跟踪窗口内不同值覆盖的元素总数。 
7. 每当窗口包含超过$K_{\max}$不同的值，我们缩小左边界，直到它再次有效。 这保持了窗口始终代表一组可行的保留值的不变性。 
8. 对于每个有效窗口，计算保留多少个元素。 答案是$n - \max(\text{kept})$，因为外面的一切都改变了。 

### 为什么它有效

 关键的不变量是任何最佳间隔$[l, r]$完全对应于对排序的不同值的连续块的选择。 该块内的任何元素都保持不变，而外部的任何元素都被强制到边界之一，因此它必然被视为已修改。 由于排序保留了值的顺序，因此任何非连续的值选择都不是最佳的：它要么会增加不同值的数量，要么会增加边界处的强制修改。 因此，最优解必须显示为在不同组的数量限制下分组频率上的最大和窗口。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, I = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort()
    
    # compress into frequencies
    vals = []
    cnts = []
    
    for x in a:
        if not vals or vals[-1] != x:
            vals.append(x)
            cnts.append(1)
        else:
            cnts[-1] += 1
    
    m = len(vals)
    
    # compute max bits per element
    # need n * k <= 8I => k <= (8I) / n
    max_bits = (8 * I) // n
    
    # find max K such that ceil(log2 K) <= max_bits
    # equivalently K <= 2^max_bits
    if max_bits >= 30:
        K = m
    else:
        K = min(m, 1 << max_bits)
    
    if K >= m:
        print(0)
        return
    
    # sliding window over distinct values
    left = 0
    current = 0
    best_keep = 0
    
    for right in range(m):
        current += cnts[right]
        
        while right - left + 1 > K:
            current -= cnts[left]
            left += 1
        
        best_keep = max(best_keep, current)
    
    print(n - best_keep)

if __name__ == "__main__":
    solve()
```该代码首先对数组进行排序并将其压缩为相等值的块。 这是至关重要的，因为所有决策仅取决于不同的价值观，而不是其多重立场。 

的计算$K$将位约束转换为允许的不同值的最大数量。 对大件的特殊处理`max_bits`避免超出 Python 整数限制，并且还涵盖约束实际上是非限制性的情况。 

滑动窗口迭代不同的值，维护一个最多具有$K$独特的元素。 变量`current`跟踪窗口内保留了多少原始数组元素。 扩展右边界会添加一个完整的块，缩小左边界会删除完整的块，从而保持正确性。 

最终答案减去最佳保存计数$n$，因为最佳窗口之外的每个元素都必然会被压缩规则改变。 

## 工作示例

 ### 示例 1

 输入：```
6 1
2 1 2 3 4 3
```排序后的数组是`[1, 2, 2, 3, 3, 4]`，频率`[1, 2, 2, 2, 1]`。 

磁盘非常小，因此只允许少量不同的值。 该算法找到最适合的连续值块并将最多的元素保留在其中。 

| 步骤| 左| 对| 窗口值| 保留元素|
 | ---| ---| ---| ---| ---|
 | 1 | 0 | 0 | [1] | 1 |
 | 2 | 0 | 1 | [1,2]| 3 |
 | 3 | 0 | 2 | [1,2,2]| 5 |
 | 4 | 1 | 3 | [2,2,3]| 6 |

 最好的窗口保留4个元素（取决于K约束），因此变化次数变为2。 

该轨迹显示分组频率如何允许算法评估整个块而不是单个元素。 

### 示例 2

 输入：```
5 10
1 1 1 1 1
```只有一个不同的值。 排序和压缩后，我们立即发现不需要减少。 滑动窗口跨越整个数组，`best_keep = 5`，所以输出为0。 

这证实了该算法自然地处理单值边缘情况，无需超出 K 检查的特殊大小写。

 ## 边缘情况

 关键的边缘情况是所有值都相同。 排序压缩产生单个块，因此滑动窗口立即覆盖整个数组。 由于只有一个不同的值，因此永远不会违反允许的限制，并且算法会正确返回零更改。 

当磁盘太小以至于只能保留一个或两个不同的值时，就会出现另一种边缘情况。 在这种情况下，滑动窗口会急剧缩小，但它仍然始终考虑连续的值块。 例如，使用输入`[1,2,3,4,5]`并且容量极小，最佳窗口将是单值块，并且算法正确地选择最大频率块，通过保留最多重复的强度来最小化变化。
