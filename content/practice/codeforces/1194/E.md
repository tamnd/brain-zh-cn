 ## 解决方案
 ## 问题理解

 我们得到了平面上与轴对齐的线段的集合。 每个部分要么完全水平，要么完全垂直。 水平线段永远不会与其他水平线段重叠，垂直线段也是如此。 相交仅发生在水平线段和垂直线段之间，并且当它们发生时，它们形成单个交叉点。 

任务是计算我们可以选择形成矩形边界的四个线段的有多少种方式。 所选线段中的两个必须是水平的，两个必须是垂直的。 每个水平线段必须与两个垂直线段相交，反之亦然，因此它们一起定义了矩形的四个边。 

重新解释问题的一个关键方法是从交叉结构的角度进行思考。 每个垂直线段定义了一组与其相交的水平线段，当我们选择两个共享至少两个公共水平邻居的垂直线段时，就会准确地形成一个矩形。 

限制允许最多 5000 个段。 三次或更差的方法是不可能的。 即使 O(n^2 log n) 或 O(n^2) 解决方案也处于临界状态，但可以接受，这表明我们应该寻找一种结构，将问题减少到有效处理对和计算重叠。 

当多个垂直段恰好共享一个共同的水平段时，就会出现一种微妙的边缘情况。 例如，如果三个垂直线段都与相同的两个水平线段相交，则每对垂直线段贡献一个矩形。 如果不对称地强制“选择两个水平线和两个垂直线”，则每个交叉点独立计数的幼稚方法可能会出现重复计算或丢失组合的风险。 

另一种故障模式是将交叉点视为独立点并计算每个单元格网格表示的正方形。 当线段很长时，这种情况就会破裂，因为相交不是点网格问题，而是区间重叠问题。 

## 方法

 蛮力策略是尝试每个四边形并检查它们是否形成矩形。 对于每个候选者，我们验证是否有两个水平线段和两个垂直线段，然后检查所有四个交叉条件。 这需要 O(n^4) 种组合，每次检查的时间复杂度为 O(1)，在最坏的情况下会导致大约 6×10^14 次操作。 这远远超出了任何可行的限度。 

我们可以通过分离水平和垂直部分来减少这种情况。 假设我们固定两个垂直线段。 当且仅当至少有两个水平线段与两个垂直线段相交时，它们才存在矩形。 如果我们知道公共水平交点的数量，比如 k，那么这对垂直线就贡献了 C(k, 2) 个矩形。 

因此，问题简化为：对于每对垂直线段，计算有多少水平线段与它们相交。 相同的逻辑可以对称地工作，但我们只需要一个方向。 

现在关键的优化是对哪些水平线与哪些垂直线相交进行编码。 对于每个垂直线段，我们可以构建与其相交的所有水平线段的列表。 然后，对于每对垂直线段，我们计算它们列表的交集的大小。 由于 n 最多为 5000，因此使用频率数组或标记技术存储和交叉这些列表足够快。 

垂直线段对加上总交集处理的最终复杂度变为 O(n^2)，这是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解四倍 | O(n^4) | O(n^4) | O(1) | O(1) | 太慢了 |
 | 配对垂直线 + 计算共同水平线 | O(n^2 + 总交集) | 最坏 O(n^2) | 已接受 |

 ## 算法演练

我们重新组织问题，使垂直线段充当水平交叉点的“桶”。 

1. 将所有段分割为水平和垂直。 这是必要的，因为只有混合对相交，并且矩形由每种类型中的两个定义。 
2. 对于每个垂直线段，计算哪些水平线段与其相交。 如果水平线段的 x 范围包含垂直 x 坐标且其 y 值位于垂直 y 范围内，则水平线段与垂直线段相交。 
3. 将这些关系存储在一个结构中，其中每个垂直方向都有一个水平索引列表。 这将几何变换为集合上的组合。 
4. 对于每对垂直线段，计算两个列表中出现的水平线数量。 这是接触两个垂直方向的水平线段的数量。 
5. 如果这个数字是k，那么这两条垂直线形成C(k, 2)个矩形，因为我们选择任意两条公共水平线作为顶边和底边。 
6. 将所有垂直对的贡献相加。 

核心推理是，每个矩形都是通过选择其左侧和右侧垂直边，然后选择与两者相交的两条水平线来唯一确定的。 这可确保每个矩形都被精确计数一次。 

### 为什么它有效

 修复任何有效的矩形。 它恰好有两个垂直边和两个水平边。 当我们处理它的一对垂直边时，两个水平边都将出现在这两个垂直边的交集列表中。 因此，该矩形被计入该垂直对的 C(k, 2) 项中。 没有其他垂直对可以生成相同的矩形，因为垂直边是由矩形的定义固定的。 这确立了计数的完整性和唯一性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def intersect(h, v):
    # h: (x1, x2, y), v: (x, y1, y2)
    x1, x2, y = h
    x, y1, y2 = v
    return (min(x1, x2) <= x <= max(x1, x2)) and (min(y1, y2) <= y <= max(y1, y2))

n = int(input())
horiz = []
vert = []

for i in range(n):
    x1, y1, x2, y2 = map(int, input().split())
    if y1 == y2:
        horiz.append((x1, x2, y1))
    else:
        vert.append((x1, y1, x2))

H = len(horiz)
V = len(vert)

# build adjacency: for each vertical, which horizontals it intersects
adj = [[] for _ in range(V)]

for vi, (x, y1, y2) in enumerate(vert):
    for hi, (x1, x2, y) in enumerate(horiz):
        if min(x1, x2) <= x <= max(x1, x2) and min(y1, y2) <= y <= max(y1, y2):
            adj[vi].append(hi)

ans = 0

# count pairs of verticals
for i in range(V):
    mark = {}
    for h in adj[i]:
        mark[h] = 1
    for j in range(i + 1, V):
        cnt = 0
        for h in adj[j]:
            if h in mark:
                cnt += 1
        ans += cnt * (cnt - 1) // 2

print(ans)
```该解决方案明确地构建了垂直线段和水平线段之间的交叉关系。 在此公式中，垂直对上的双循环是不可避免的，但每个对都使用哈希成员资格检查进行处理，这可以保持交集计数的效率。 

一个微妙的点是每个垂直领域使用一个字典（或集合）。 这可以避免在计算交叉点时进行 O(n) 扫描。 最后的组合步骤使用组合恒等式 C(k, 2)，确保我们计算的是水平线对而不是单个交叉点。

 ## 边缘情况

 当几个垂直线段共享完全相同的一组相交水平线时，就会出现退化配置。 在这种情况下，每对垂直线为每对共享水平线贡献一个矩形，因此算法正确地使用 C(k, 2) 而不是 k。 

另一种情况是，一条垂直线与许多水平线相交，但大多数其他垂直线仅与一个子集相交。 成对交集逻辑确保只有公共水平线起作用，从而防止独立交集的过度计数。
