 ## 解决方案
 ## 问题理解

 我们将一个芯片放置在从 0 到 n 索引的线性单元条的右端。 两名玩家从最右边的位置 n 开始交替移动，每次移动都包括将筹码向左移动 1、2 或 k 个位置，只要筹码保持在条带内即可。 不能做出任何合法动作的玩家就输了。 

任务是确定每个独立游戏中第一个玩家是否在最佳玩法下强制获胜。 

约束n可以大到10^9，最多查询100场比赛。 这立即排除了从 0 到 n 的所有位置上的任何动态编程，因为即使每个测试用例的线性扫描也已经太大了。 任何正确的解决方案都必须将游戏简化为每个测试用例的恒定时间或对数时间分类。 

当 n 相对于 k 较小时，会出现微妙的边缘情况。 例如，当n = 0时，起始位置根本没有有效的移动，因此第一个玩家立即失败。 另一种情况是当 n < k 时，“k 步”不可用，只能移动 1 或 2 个物质，这会改变获胜位置的局部结构。 盲目地假设所有三个动作始终可用的天真尝试会错误地将这些状态视为与大 n 相同。 

## 方法

 考虑这个问题的自然方法是把它想象成一条线上的减法游戏：从位置 i 开始，你可以移动到 i−1、i−2 或 i−k。 暴力解决方案将使用 DP 计算从 0 到 n 的每个位置的获胜和失败状态，其中如果该位置至少有一次移动到失败的位置，则该位置获胜。 这是正确的，因为游戏是有限的且非循环的。 

然而，这种方法每个测试用例的成本为 O(n)，并且当 n 达到 10^9 时，它变得不可行。 即使将所有情况的总数减少到 O(n) 仍然是不可能的。 

关键的观察结果是，除了长度为 k 的单次长跳之外，移动集几乎是均匀的。 一旦位置距离 0 足够远，游戏的行为就会变成周期性的，因为减去 1 和 2 会生成重复结构，而额外的 k 步移动仅通过其与位置模 k+1 的相互作用才起作用。 

如果我们检查由移动 {1,2} 生成的亏损头寸，它们会形成周期为 3 的重复模式：当仅存在移动 1 和 2 时，与 0 模 3 一致的头寸正在亏损。 引入 k 移动仅在达到 i−k 会改变我们是否可以跳入失败状态的位置打破这种模式。 事实证明，这种相互作用仅取决于 n 是否能被 3 整除以及 k 是否与 1 模 3 全等，更重要的是 n 是否至少为 k。 

当 n ≥ k 时，位置 i = n 的行为类似于标准减法游戏，具有 i−k 的“特殊快捷方式”。 决定性的事实是，k 步只有当它从 1-2 游戏的获胜区域跳入失败的剩余类别时才有意义。 该对齐仅取决于 n mod 3 和 k mod 3。分析转换图后，最终分类减少为对这些残基的恒定时间检查，并在 n < k 时进行小调整，其中 k 移动不可用。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力DP | 每次测试 O(n) | O(n) | 太慢了 |
 | 周期性+残留分析| 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从概念上将游戏视为从0开始向上的落位检测问题，但我们只需要n的分类。

1. 首先处理n < 2的情况。当n = 0时，玩家没有动作。 当 n = 1 时，仅存在向 0 移动，并且它立即给对手带来失败状态，因此结果直接从这些基本结果得出。 
2. 当k大于n时，k大小的移动是不可能的。 该游戏简化为一个减法游戏，步数为{1,2}。 在这个简化的游戏中，位置在长度为 3 的循环中重复，因为从任何位置 i 都会转移到 i−1 和 i−2，这会导致周期性的失败模式，其中每三个位置都会失败。 
3. 当 k ≤ n 时，k 步棋被激活。 从位置 n 开始，我们可以选择跳转到 n−k，因此我们需要检查该跳转是否可以通过落在简化结构的失败状态中来强制获胜。 关键是，在 {1,2} 游戏中，失败状态正是 i mod 3 = 0 的状态。 
4. 我们计算 n mod 3 和 k mod 3 并检查 k 跳跃是否落在失败的残数上。 如果 n−k 是基础游戏中的失败位置，那么当前位置就是获胜位置，因为我们可以直接移动到那里。 
5. 如果所有动作都没有导致失败状态，则当前位置为失败。 

决定性的简化是我们从不显式计算所有状态； 我们只对留数以及单次长跳是否会破坏 3 周期结构进行推理。 

### 为什么它有效

 不变量是，没有 k 步棋的游戏具有完全确定的周期为 3 的周期性失败模式。k 步法从每个状态最多引入一个额外的传出边，并且只有当该边将一个状态连接到基础结构中已经失败的位置时，该边才有意义。 由于丢失状态是周期性的，因此检查成员资格减少为检查 n−k 模 3。因此，n 处的决策仅取决于额外的边是否连接到丢失的残差类，并且所有进一步的递归都会崩溃为相同的周期性分类。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n, k):
    if n == 0:
        return "Bob"
    if n == 1:
        return "Alice"

    if k > n:
        return "Alice" if n % 3 != 0 else "Bob"

    if n % 3 == 0:
        return "Bob"

    return "Alice"

def main():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        print(solve_case(n, k))

if __name__ == "__main__":
    main()
```该代码首先分离了琐碎的边界情况，因为这些是 k 步可能不相关或游戏立即结束的唯一地方。 当 k 超过 n 时，我们会回到经典的减法游戏，即第 1 步和第 2 步，这会产生一个简单的模 3 失败结构。 当 k 可用时，唯一需要的稳定特征是 n 是否是 3 的倍数，因为额外的移动不会改变该游戏公式的周期性失败结构。 

一个常见的实现陷阱是混合 k > n 和 k ≤ n 的情况，同时仍然统一应用模规则。 这错误地假设 k-move 总是相关的，这破坏了小 n 的正确性。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n, k = map(int, input().split())
            if n == 0:
                out.append("Bob")
            elif n == 1:
                out.append("Alice")
            elif k > n:
                out.append("Alice" if n % 3 != 0 else "Bob")
            else:
                out.append("Bob" if n % 3 == 0 else "Alice")
        return "\n".join(out)

    return solve()

 ## 边缘情况

 当 n = 0 时，筹码从没有出棋的位置开始。 该算法在任何模块化推理之前显式返回 Bob，匹配起始玩家立即失败的事实。 

当n = 1时，只有一个移动存在，它直接导致0。由于0是失败状态，所以算法返回Alice，反映出第一个移动强制获胜。 

当k>n时，跳远是不可能的。 在这种情况下，代码正确地忽略 k 并应用 {1,2} 游戏的模 3 结构。 仍然尝试评估 n−k 的粗心实现会错误地将负位置视为有效转换。 

当n是3的倍数时，该位置被分类为在基础结构中丢失。 当 k ≤ n 时，无论 k 为何，该算法都会返回 Bob，这与从此类位置开始的所有移动都落在获胜状态这一事实是一致的。
