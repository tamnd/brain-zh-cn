 ## 解决方案
 ## 问题理解

 我们有几个独立的网格。 每个网格都是一个字符矩阵，其中每个单元格要么已经是黑色，要么仍然是白色。 我们被允许一次将白色细胞变成黑色细胞。 目标是使网格包含至少一个“十字”。 

通过选择一行来定义十字`x`和一列`y`这样行中的每个单元格`x`是黑色的，列中的每个单元格`y`是黑色的。 换句话说，我们想要一个全黑的行和一个全黑的列，并且它们在一个单元格处相交。 

对于每个查询，我们必须计算需要重新绘制的最小白细胞数量，以便至少有一对这样的白细胞`(row, column)`存在。 

这些限制迫使我们仔细思考效率。 所有查询的单元总数最多为 4 × 10^5，因此任何处理每个单元恒定次数的解决方案都是可以接受的。 然而，任何尝试显式测试每个行列对的方法都会太慢，因为在最坏的情况下这将是 O(nm(n+m))。 

一个天真的错误是认为我们可以贪婪地选择任何候选行和列而不评估真实成本。 这在多个行和列几乎完整但在一些分散的位置有所不同的网格上失败。 例如，如果一行仅缺少一个单元格，而一列缺少多个单元格，则贪婪地选择行而不考虑列交互可能会低估或高估所需的重绘成本。 

当多对共享相同的缺失单元时，会出现另一种微妙的故障情况。 重新绘制单个单元格可能会同时修复行和列，因此单独处理行完成和列完成会导致错误的答案。 

## 方法

 蛮力的想法很简单。 对于每一个可能的对`(x, y)`，我们计算行中有多少个白细胞`x`加上列中存在多少个`y`，但我们必须避免重复计算交叉单元格。 如果该交集是白色的，则它会在朴素总和中被计数两次，因此我们将其减去一次。 

这是有效的，因为如果我们想要行`x`全黑，我们必须重新绘制其中的所有白色单元格。 同样对于列`y`。 这些重绘操作的​​联合给出了候选成本。 尝试所有对可以保证正确性，但成本却太高。 计算行和列计数是 O(nm)，检查所有对是 O(nm)，导致每个网格的 O(nm) 已经是边界，并且任何更详细的重新计算在许多查询中都变得太慢。 

关键的观察是一对的成本`(x, y)`仅取决于三个预先计算的量：行中白细胞的数量`x`, 列中白细胞的数量`y`，以及是否`(x, y)`已经是黑色或白色。 一旦知道这些，每个候选对的评估时间复杂度为 O(1)。 这将问题简化为一次计算行和列统计数据，然后再次扫描所有单元格以找到最佳对。 

相交校正使问题变得不平凡：如果`(x, y)`是白色，那么它就包含在行和列白色计数中，所以我们减一。 

我们通过迭代所有单元来隐式尝试所有对，将每个单元视为潜在的交叉中心。 这已经足够了，因为每个有效的交叉必须以某个单元格为中心，并且每个候选中心对应于唯一的行和列对。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解所有对 | O(n²m + nm²) | O(1) | O(1) | 太慢了 |
 | 预计算行/列 + 扫描单元 | O(纳米) | O(n+m) | 已接受 |

 ## 算法演练

 ### 1. 计算每行和每列的黑色和白色单元格

 我们扫描整个网格一次。 对于每一行，我们计算它包含多少个白色单元格，对于每一列，我们执行相同的操作。 这使我们能够立即知道需要多少次重绘操作才能完全变黑一行或一列。 

### 2. 存储网格状态以进行相交检查

 我们保留每个单元格的布尔或字符表示，以便我们可以检查特定的交叉单元格是否已经是黑色或必须被绘制。 这很重要，因为交叉单元格在行和列总计中被计数两次。 

### 3. 尝试将每个单元格作为潜在的交叉中心

 对于每个单元格`(i, j)`，我们计算行的成本`i`全黑和柱状`j`全黑。 成本是：

 行中白细胞的数量`i`加上列中白细胞的数量`j`，如果单元格减 1`(i, j)`是白色的。 

减法避免了对相同的重绘操作进行重复计算。 

### 4. 跟踪所有候选人的最低成本

 我们将答案初始化为一个大值，并为每个单元格更新它。 最小的计算值是该查询的答案。 

### 为什么它有效

 每个有效的交叉必须对应于一些行和列对`(x, y)`。 创建该交叉的成本仅取决于填充这两条线中缺失的单元格。 行外的任何重绘操作`x`或列`y`是不必要的并且不能改进该对。 由于我们评估了所有可能的中心`(x, y)`，我们必须评估最佳交叉配置，保证找到最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n, m = map(int, input().split())
        grid = [input().strip() for _ in range(n)]

        row_white = [0] * n
        col_white = [0] * m

        for i in range(n):
            for j in range(m):
                if grid[i][j] == '.':
                    row_white[i] += 1
                    col_white[j] += 1

        ans = float('inf')

        for i in range(n):
            for j in range(m):
                cost = row_white[i] + col_white[j]
                if grid[i][j] == '.':
                    cost -= 1
                if cost < ans:
                    ans = cost

        print(ans)

if __name__ == "__main__":
    solve()
```该实现将预处理与评估分开。 首先，单次计算行和列白色计数。 然后每个单元格被视为潜在的交点并在恒定时间内进行评估。 关键的微妙之处是当交叉单元格已经是白色时减一，因为否则它会被计数两次。

 ## 边缘情况

 关键的边缘情况是交叉单元格为白色并且对行和列重绘计数都有贡献。 例如：

 输入：```
1
2 2
..
..
```行白人是`[2,2]`和柱白是`[2,2]`。 对于细胞`(1,1)`，朴素成本是`2 + 2 = 4`，但这重复计算`(1,1)`。 正确的成本是`3`。 该算法正确地减一，产生`3`，所有单元格的最小值为`3`，相当于绘制共享中心的一整行和一整列。 

另一种边缘情况是当行或列已经全黑时。 那么最佳解决方案就是简单地完成另一个维度，并且算法自然返回最小值，因为其中一个计数为零。 

最后一种情况是存在多个最佳中心。 由于该算法统一扫描所有单元并且仅跟踪最小值，因此它自然地处理平局而无需任何特殊逻辑。
