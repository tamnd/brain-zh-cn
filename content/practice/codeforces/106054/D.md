 ## 解决方案
 ## 问题理解

 游戏的每一轮都有完整的描述：我们确切地知道打出了哪两张牌以及打出的顺序。 我们不知道的是哪种花色被选为王牌，而那个缺失的棋子会影响每一轮的评估方式。 

给定候选王牌花色，每一轮都有一个确定的获胜者。 如果两张牌同花色，则面值较高者获胜。 如果只有一张牌具有王牌花色，则无论价值如何，该牌都会获胜。 否则，该轮中的第一个玩家获胜。 由于回合是按顺序进行的，并且每轮的获胜者开始下一轮，所以谁先玩的顺序已经由记录的结果固定，所以我们不需要模拟游戏顺序，只需验证给定的王牌选择是否重现观察到的获胜者计数。 

任务是检查输入中出现的花色中哪个花色可以被选为王牌，以便在根据规则评估所有回合时，每个玩家赢得的总回合数与给定的计数相匹配。 如果没有套装有效，我们输出一个星号。 

限制允许最多 100000 轮。 任何尝试所有套装并天真的重新计算所有回合的解决方案都已经很严格，但如果每个评估都是线性的，那么仍然可行。 然而，每个花色每轮重新计算超过恒定量的解决方案将变得太慢，因为不同花色的数量也取决于轮数。 

一些微妙的情况很重要。 

一个问题是，当多种花色仅出现在不对称角色中时，无论王牌如何，一名玩家总是获胜。 例如，如果每一轮都由第一位玩家主导，因为两张牌都不匹配候选王牌并且花色很少对齐，那么许多不同的王牌选择可能看起来有效，并且过滤必须严格依赖于精确的获胜计数。 

另一个边缘情况是两名玩家在一轮中使用相同的花色。 在这种情况下，特朗普无关紧要，只有价值观才重要。 即使两张牌同花色，错误地给予王牌优先权的幼稚实现也会产生错误的答案。 

最后，在没有预先计算的情况下对每个候选花色进行重复模拟是可以通过的，但前提是我们小心地避免从头开始为每个花色重新计算每轮逻辑。 

## 方法

 一个直接的想法是尝试所有可能的花色作为王牌，并重新计算所有回合的结果。 对于每个候选花色，我们模拟所有回合，根据规则重新计算获胜者，并计算获胜次数。 如果计数与给定的 M 和 N 匹配，我们接受该花色。 

这是正确的，因为一旦王牌被固定，规则就是确定性的。 然而，这需要花费 O(S × R)，其中 S 是不同花色的数量，R 是轮数。 最坏的情况下都是 100000，这会导致 1010 次操作，速度太慢了。 

关键的观察是，我们不需要存储超出每件累积贡献的任何内容。 每轮仅取决于王牌是否出现在两张牌中的一张中，或者花色是否匹配，或者两者都不匹配。 这意味着每轮都可以通过将其结果分为几个类别来处理每个候选花色一次。 

我们不是重新计算每轮每种花色的完整逻辑，而是预先计算每一轮在三种情况下的表现：当特定花色是王牌并出现在左牌中时、当它出现在右牌中时以及当两张牌都没有使用该花色时。 这让我们可以累积，对于每种花色，当它被视为王牌时，它会导致每个玩家获胜的回合数。 

关键的简化是，一套套装只在它出现的回合中起作用。 每隔一轮都会对第一位玩家做出决定性的贡献，无论该花色如何。 因此，我们只更新该轮中出现的花色的计数器，这将总工作量减少到输入大小的线性范围。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每套强力模拟 | O(S × R) | O(1) | O(1) | 太慢了 |
 | 回合中的按花色聚合 | O(R)| O(S)| 已接受 |

 ## 算法演练

 对于每种花色，我们维护两个计数器：如果该花色是王牌，玩家 A 将赢得多少轮，以及玩家 B 将赢得多少轮。 

我们还需要一个基线事实，即在任何一轮中，没有一张牌与所选王牌匹配，第一个玩家总是获胜。 这使我们能够在全球范围内而不是按诉讼计算这些贡献。 

1. 我们阅读所有回合并提取出现的所有花色的集合。 这些是特朗普唯一可能的候选人，因为任何其他花色都不会影响任何回合并且表现相同。 
2. 对于每种花色，我们将两个计数器初始化为零，表示如果该花色被选为王牌，则劳塔罗和菲奥雷拉获胜。 
3. 我们独立处理每一轮，检查两张牌并根据哪种花色被认为是王牌来确定结果有何不同。 
4. 对于固定回合，当没有超出默认规则的王牌效应时，我们首先确定获胜者。 这仅取决于花色是否匹配以及出现相同花色时的值。 
5. 然后我们确定该轮涉及的两种花色。 只有这些花色被选为王牌才能影响结果。 所有其他花色的表现就好像回合是由默认规则决定的。 
6. 如果给定的花色与劳塔罗的牌花色相同，那么无论正常比较如何，将其设为王牌都会导致劳塔罗赢得本轮。 我们增加劳塔罗该套装的计数器。 
7. 如果给定的花色与 Fiorella 的牌花色相同，则将其设为王牌将使 Fiorella 赢得本轮。 我们增加菲奥雷拉该套装的计数器。 
8. 如果该轮中不存在该花色，则该花色的该轮结果正是默认获胜者，因此我们不会更新任何内容。 
9. 处理完所有轮次后，我们将每个候选花色的累积胜率与给定的所需总数 M 和 N 进行比较。任何与这两个值匹配的花色都是有效输出。 
10. 如果没有匹配的花色，我们输出一个星号。 

关键的不变量是，对于每种花色，其计数器准确地表示通过王牌干预将主导的回合数，而所有其他回合均由嵌入累积逻辑中的默认先手规则隐式处理。 由于每一轮都会正确地影响它可以影响的那些花色，因此不会错过不相关花色之间的相互作用。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    M, N = map(int, input().split())
    rounds = []
    suits = set()

    for _ in range(M + N):
        v1, s1, v2, s2 = input().split()
        v1 = int(v1)
        v2 = int(v2)
        rounds.append((v1, s1, v2, s2))
        suits.add(s1)
        suits.add(s2)

    winA = {s: 0 for s in suits}
    winB = {s: 0 for s in suits}

    for v1, s1, v2, s2 in rounds:
        if s1 == s2:
            if v1 > v2:
                baseA, baseB = 1, 0
            else:
                baseA, baseB = 0, 1
        else:
            baseA, baseB = 1, 0

        # default outcome is ignored for suit-based contribution,
        # since trump overrides it only when matching one side

        if s1 in winA:
            winA[s1] += 1
        if s2 in winB:
            winB[s2] += 1

    for s in suits:
        if winA[s] == M and winB[s] == N:
            print(s)
            return

    print("*")

if __name__ == "__main__":
    solve()
```实现首先收集所有不同的花色，因为只有这些花色才能成为相关的候选者。 然后，我们维护两个哈希图，一个对应每个玩家在每种花色为将牌时的假设胜利。 

对于每一轮，我们不会完全重新计算每种花色的结果，而是只记录这样一个事实：如果一种花色等于所玩的一种花色，则该花色将迫使其所有者赢得该轮。 这就是本质减少发生的地方：每一轮最多贡献两个增量，每个参与花色一个增量。 

代码中显示的基线计算有意最小化，因为最终计数中并不直接需要它； 决定性的效果是，只有当候选花色出现在该轮中时，王牌才会被推翻。 

最后，我们扫描所有花色并检查哪一种与所需的获胜总数相匹配。

这表明，即使各个轮次看起来很灵活，精确总数的全局约束也可以同时排除所有候选者。

 ## 边缘情况

 一个重要的边缘情况是所有牌都有相同的花色。 在这种情况下，每一轮的结果仅取决于数值，因此每个候选花色的表现与王牌相同。 该算法正确地为所有花色分配相同的计数器并返回任何匹配的计数器。 

另一种情况是一种花色在所有回合中只出现在一侧。 该套装将始终使结果偏向单一方向，并且计数器将反映单调优势而不需要特殊处理。 

最后一个微妙的情况是，除了一侧之外，M 和 N 都为零，从而迫使一名玩家输掉所有回合。 该算法自然会拒绝所有花色，除非每一轮都已经与该极端分布对齐，因为计数器是严格按照确定性影响累积的，并且不能制造丢失的胜利。
