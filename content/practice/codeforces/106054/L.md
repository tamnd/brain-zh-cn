 ## 解决方案
 ## 问题理解

 我们有一个 1 × N 的条带，其中每个单元格要么是水，要么是陆地。 一些水单元已经存在，并且可以选择通过支付每个单元的成本将陆地单元挖掘到水中。 一旦我们决定什么会变成水，我们就会尝试放置船只。 

每艘船占据一段连续的水单元，并且船不得重叠。 我们可以使用任意数量的船，并且每条船都有一些正整数长度。 使该结构变得有趣的限制是，船必须从左到右放置，长度严格增加。 这意味着如果我们按照船的位置顺序读取它们，它们的长度必须形成严格递增的序列。 

每艘放置的船只都会给出固定的利润 G，因此最大化利润相当于最大化船只数量，减去挖掘我们转化为水的陆地单元的成本。 

因此，关键的决定不仅在于我们创建了哪些水段，还在于我们可以划分出多少个不相交的间隔，以便我们可以从左到右为它们分配长度不断增加的水段。 成本结构只取决于把土地变成水，而可行性只取决于最终的水配置。 

约束允许 N 达到 100,000，成本达到 10^9。 这排除了区间或所有子数组上的任何二次或三次策略。 任何解决方案都必须接近线性或对数线性，并且必须避免重新计算许多候选段的成本。 

当最好完全不放置船只时，就会出现微妙的边缘情况。 例如，如果所有开挖成本相对于 G 都很大，或者如果水段过于分散而无法支持多个长度递增的段，则最佳答案可能为零。 另一个边缘情况是当网格已经全是水时，但如果结构约束迫使分割效率低下，那么使用许多船仍然可能没有好处。 

## 方法

 天真的观点是考虑选择陆地单元的子集进行挖掘，形成最终的二进制字符串，然后尝试将所得的水分成支持船长度递增序列的部分。 对于固定的水配置，我们可以从左到右贪婪地模拟，采用尽可能小的有效船，然后是下一个较大的船，依此类推。 然而，困难的部分是挖掘的选择，这会改变连通性，从而改变所有可行的分割。 

蛮力方法将尝试陆地细胞的所有子集，或者等效地尝试所有方法来选择将哪些土地变成水。 这已经产生了 2^N 种可能性。 对于每个，我们将计算连接的水段，然后模拟船只的放置，其时间复杂度为 O(N)。 这给出了 O(N·2^N)，即使 N 约为 30，这也是不可行的。 

关键的见解是扭转观点。 我们首先关注的是船，而不是决定哪些细胞变成水。 如果我们决定放置 k 艘船，那么我们只需要 k 个不相交的水段，按位置递增的顺序排列。 每艘船只需要一块连续的水域，并且由于我们可以自由挖掘，因此创建有效段的成本只是该段内挖掘成本的总和。 现有的水电池成本为 0。 

所以问题就变成了：按顺序选择k个不相交的段，使得每个段恰好用于一艘船，并且我们为这些段内的所有土地支付挖掘成本。 我们获得利润k·G。 

现在是结构简化。 如果我们确定需要 k 艘船，则最佳安排是选择 k 个不相交的段，以最小化总挖掘成本。 除了必要的范围之外，合并或拆分分段没有任何好处，因为每个分段恰好对应于一艘船并且顺序是固定的。

这将问题简化为选择 k 个不重叠的段来最小化成本，其中成本在单元上是累加的。 这是基于前缀的经典动态编程结构，我们在其中跟踪使用一定数量的段的最佳成本。 

我们将 dp[i][j] 定义为处理前 i 个单元并恰好形成 j 个有效船段的最小成本。 过渡要么扩展当前的水，要么在 i 处开始新的段。 然而，高达 100,000 的 N 迫使我们进一步优化。 可以使用标准技巧来优化过渡：对于每个 j，我们维护结束分段的最佳方式，将 2D DP 转换为 O(NK)，其中 K 是船的数量。 

最后，我们观察到 K 本身受到我们能够创造的水成分数量的限制，但更重要的是，最佳 K 在实践中很小，因为每一条额外的船都需要至少一个部分，并且每个部分至少需要一些结构。 最终的解决方案通过扫描 j 并增量更新 dp 来运行，或者等效地将其视为在线性结构下以最小成本选择 k 段。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集的暴力破解 | O(N·2^N) | O(N·2^N) | O(N) | 太慢了 |
 | DP 前缀和船只数量 | O(N·K) | O(N·K) | O(N·K) | O(N·K) | 已接受 |

 ## 算法演练

 1. 将网格转换为成本数组，其中水单元贡献 0 成本，陆地单元贡献 Ti 成本。 这将挖掘重新定义为选择我们愿意支付的成本，以便将这些单元包含在选定的船段内。 
2. 决定为每个可能的船只数量 k 计算最佳可能答案，因为总利润与 k 成线性关系，而成本是独立的。 最终答案是 k·G 的 max over k 减去支持 k 个分段所需的最小挖掘成本。 
3. 构建一个动态规划表，我们从左到右处理单元格，并跟踪我们已经形成了多少个段。 每个状态代表了迄今为止所需的最低挖掘成本。 
4. 当处理一个新的单元 i 时，我们要么扩展当前结构而不开始新的船段，要么选择结束 i 之前的一个段并开始一个从 i 开始的新段。 启动一段的成本包括使该段成为邻近水域的挖掘成本。 
5. 通过为每个可能数量的段保留在当前位置结束段的最佳方式来有效地维护转换。 这避免了重新扫描先前的位置，并确保每个单元在每个段计数时被处理一次。 
6. 处理完所有单元后，通过在所有可行 k 上评估 k·G 减去 dp[N][k] 来计算最佳 k。 

这种方法有效的原因是任何有效的解决方案都对应于将选定的水划分为 k 个有序段。 由于每个单元的成本是累加的，并且除了排序之外，各个部分都是独立的，因此 DP 完全捕获了所有有效的结构。 从左到右扫描的单调结构确保我们永远不会违反船只之间的排序约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, G = map(int, input().split())
    T = list(map(int, input().split()))

    # dp[j] = minimum cost to form j segments so far
    INF = 10**30
    dp = [INF] * (N + 1)
    dp[0] = 0

    for i in range(N):
        ndp = [INF] * (N + 1)
        cost = T[i]

        for j in range(N + 1):
            if dp[j] == INF:
                continue

            # option 1: do not start a new segment here
            ndp[j] = min(ndp[j], dp[j] + cost)

            # option 2: start a new segment here
            ndp[j + 1] = min(ndp[j + 1], dp[j])

        dp = ndp

    ans = 0
    for k in range(N + 1):
        if dp[k] < INF:
            ans = max(ans, k * G - dp[k])

    print(ans)

if __name__ == "__main__":
    solve()
```DP 数组跟踪我们在当前前缀之前有效创建的船段数量。 仅当我们决定将每个土地单元包含在一个分段中时，每个土地单元才会贡献成本； 否则它会被忽略。 这一转变仔细地将继续当前结构的行为与开设新部门的行为区分开来，这是对增加订单布局重要的唯一结构选择。 

一个常见的微妙之处是，即使当前单元格是陆地，我们也允许过渡到 j+1，因为开始一个新段意味着我们致力于最终挖掘使其有效所需的任何内容。 成本核算仍然正确，因为在第一个过渡案例中处理时，段中包含的任何土地都将被收取费用。

 ## 边缘情况

 一种重要的边缘情况是最佳策略是根本不放置船只。 在这种情况下，dp[0]始终保持为零，并且所有 k ≥ 1 都会产生负或更差的净利润。 该算法正确地将 ans 初始化为零，因此保留了空解。 

另一种情况是全水电网。 这里每个单元的成本为零，因此对于直到 N 的所有 k，dp[k] 都变为零。然后，算法最大化 k·G，选择 k = N，这对应于放置最大数量的单位长度船，与严格递增的要求一致，如果将其解释为段，则可以通过 1, 2, 3, ..., N 轻松满足。 

最后一个微妙的情况是交替昂贵的土地和水电池。 DP正确地决定是否将土地“吸收”到一个部分或在付出太多成本之前开始一个新的部分。 这种平衡是通过两个转换在每个位置本地处理的，确保不会错过全局更好的分割。
