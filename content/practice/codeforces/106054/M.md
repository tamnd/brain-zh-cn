 ## 解决方案
 ## 问题理解

 我们得到了一张由无向道路连接的城市图，所有道路的长度都相等。 Marco 从城市 1 出发，必须到达城市 2。每一“天”，他都会沿着图中至少包含 1 条、最多 K 条边的简单路径行走，然后停下来。 第二天从前一天结束的地方开始。 完整的旅程是这样的日常步行的序列，并且在将路线从 1 到 2 划分为有效的每日路段的所有可能方法中，仅考虑那些使用尽可能少的天数的方法。 

任务不是找到边缘中的最短路径，而是考虑步行的所有最短可能的日内分解，这些步行的串联形成从 1 到 2 的任何步行。即使步行重新访问城市或边缘，它仍然是有效的； 重要的是，每一天都是一段有限长度的步行的连续部分。 

输出是不同的最佳日分解的数量以 998244353 为模。 

关键约束是 N、M、K ≤ 2000。这立即表明 O(N^2) 或 O(MK) 风格的动态规划是合理的，而 N 中的任何三次方都是边界线，但通过仔细的类似 BFS 的预处理仍然可以接受。 

一个微妙的边缘情况是，边缘方面的最短路径并不直接相关。 例如，如果 K 很大，Marco 可以在一天内完成整个最短路径，但也可能存在多个相同长度的不同步行，甚至更长的步行，由于不同的分区点，仍然遵循最小天数。 

另一个重要的角落是当图表包含循环时。 朴素的最短路径推理会忽略重访，但这里完全允许一天内重访，这意味着计数从根本上讲是计算受约束的行走，而不是路径。 

## 方法

 直接解释建议枚举从 1 到 2 的所有可能游走，然后将它们分成长度至多为 K 的段，并计算最小化段数量的有效分解。 这会立即失败，因为行走次数随着长度呈指数增长，甚至限制为最短天数序列也不会减少组合爆炸。 

正确的视角是逆向分解。 我们不考虑完整的旅程，而是考虑达到由“几天后到达某个城市，并在相同规则下完全使用到达该城市所需的最少天数”定义的状态。 

第一个结构观察是，到达节点的最小天数与我们如何计算各个步行的方式无关，并且可以通过将每个节点视为一个状态并将每个转换视为最多允许 K 个步骤的一天来计算。 从一个节点出发，一天可以到达图中K条边内的任意节点。 这将问题转化为隐式图上的分层最短路径，其中边表示“K 步内的可达性”。 

然而，我们还需要计算一天最多使用 K 条边从 u 到 v 有多少种不同的方式，因为在同一城市结束的不同日常步行是不同的。 

这表明有两层计算。 首先，我们计算每对 (u, v) 从 u 到 v 的长度最多为 K 的步行次数。其次，我们在压缩图上运行一条最短路径，其中每个这样的路径就像一天的加权过渡，并同时计算实现最短日距离的方法数量。

第一层是使用 DP 对步数进行标准有界长度步行计数。 我们维护 dp[t][v] 来表示从源开始的长度为 t 的行走次数，对所有源重复或通过重复向量转换计算。 由于 N 为 2000，K 为 2000，因此我们在每个源中使用 O(NMK) 中的邻接转移重复乘法或 O(MK) 中的优化邻接列表 DP，但如果我们将其与类似 BFS 的传播相结合，则不需要显式地使用所有对。 

关键的优化是避免全对DP。 相反，我们在“日层”上执行 BFS，其中每一层转换都需要在图上的一个多源 DP 中使用最多 K 个步骤来计算从当前边界到下一个边界的路径数量。 

一旦我们有了从当前层到下一层的路径数量，我们就会扩展直到第一次到达节点 2； 该层数就是最少天数。 然后我们计算各层的 DP 以累积计数。 

核心思想是：每一天都是一次有界长度的行走，我们将每一天视为一条超边，其在日图中的权重为1，但其重数为端点之间长度≤K的行走次数。 

然后我们运行最短路径+依赖这个隐式超图。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 所有路径和分区的强力枚举 | 指数| 指数| 太慢了 |
 | 日层上的多源 DP + BFS | O(N·M·K) | O(NM) | 已接受 |

 ## 算法演练

 1.对于每个起始城市u，预先计算使用最多K步到达每个城市v的方式数量。 这是通过在步行长度上运行 DP 来完成的，其中每个步骤都沿着边缘传播计数。 结果是一个转换矩阵 T[u][v]，给出了从 u 到 v 的有效每日步行次数。 
2. 将每个城市视为新图中的一个节点，其中存在从 u 到 v 的有向加权转移，权重为 T[u][v]，代表从 u 到 v 的所有可能的一日步行。 
3. 根据天数而不是边数从节点 1 运行 BFS 式最短路径。 维护一个距离数组 dist[v]，存储到达 v 所需的最小天数，以及一个方法数组，存储达到该最小值的方式数量。 
4. 初始化 dist[1] = 0 和ways[1] = 1，所有其他距离为无穷大。 
5. 使用队列按 dist 升序处理节点。 当处理节点 u 时，使用转换 T[u][v] 松弛所有节点 v。 候选距离为 dist[u] + 1。如果小于 dist[v]，则覆盖 dist[v] 并设置ways[v] =ways[u] * T[u][v]。 如果相等，则累加ways[v] +=ways[u] * T[u][v]。 
6. 继续，直到处理完所有可达节点。 答案是与 dist[2] 相对应的ways[2]，通过构造它是最小的。 

它之所以有效，是因为将问题分成两个独立的结构。 内部 DP 正确计算了具有有限长度 K 的城市对之间的所有有效每日步行。外部 BFS 将每次此类每日步行视为几天内最短路径问题中的单个原子步骤。 由于每次转换的天数成本相同，因此 BFS 保证最少的天数。 因为我们以正确的多重性聚合所有可能的转变，所以计数 DP 正确地对所有不同的最小日分解求和，而无需混合不同日长的路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def main():
    n, m, k = map(int, input().split())
    adj = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append(v)
        adj[v].append(u)

    # dp_prev[v] = number of ways to reach v in current step length
    # we compute cumulative up to k steps from each source via multi-source DP

    # T[u][v] = number of walks from u to v with length 1..k
    T = [[0] * n for _ in range(n)]

    for s in range(n):
        dp = [0] * n
        dp[s] = 1
        for _ in range(k):
            ndp = [0] * n
            for u in range(n):
                if dp[u]:
                    val = dp[u]
                    for v in adj[u]:
                        ndp[v] = (ndp[v] + val) % MOD
            dp = ndp
            for v in range(n):
                T[s][v] = (T[s][v] + dp[v]) % MOD

    dist = [10**18] * n
    ways = [0] * n
    dist[0] = 0
    ways[0] = 1

    from collections import deque
    q = deque([0])

    while q:
        u = q.popleft()
        for v in range(n):
            if T[u][v] == 0:
                continue
            nd = dist[u] + 1
            w = (ways[u] * T[u][v]) % MOD
            if nd < dist[v]:
                dist[v] = nd
                ways[v] = w
                q.append(v)
            elif nd == dist[v]:
                ways[v] = (ways[v] + w) % MOD

    print(ways[1] % MOD)

if __name__ == "__main__":
    main()
```第一部分通过模拟从每个源开始的 K 步步行 DP 来构建转换矩阵 T。 每次迭代都会将所有部分行走延伸一条边并累积端点，因此在 K 次迭代之后，T[s][v] 会计算从 s 到 v 的长度最多为 K 的所有行走。 

第二部分对该隐式图执行最短日遍历。 dist 跟踪最小天数，ways 累积计数以 998244353 为模。类似 BFS 的结构是有效的，因为每次转换总是花费 1 天。 

一个微妙的点是，当从 u 放松时，我们显式地循环所有 v，这在 N ≤ 2000 时是可以接受的，因为转换是密集的但有界的。 由于 K 和 M 的限制，复杂性仍然在限制范围内。

 ## 边缘情况

 对于 K ≥ 1 的直接单边图 1-2，算法设置 T[1][2] = 1，BFS 立即给出 dist[2] = 1 和ways[2] = 1。不存在替代转换，因此不会发生过度计数。 

对于有周期的图表，例如 1-3-1，DP 可以正确计算一天内的重访路线。 例如，当 K = 2 时，步行 1→3→1→3 与 1→3→3 分开计数，并且两者独立地对 T[1][3] 做出贡献。 BFS 层将两者视为不同的转换，从而保留最终答案的多样性。 

对于较大的 K，自然会包含所有短于 K 的路径，因为 DP 会累积所有中间长度，从而确保缩短步行不会消除影响最小日结构的有效分解。
