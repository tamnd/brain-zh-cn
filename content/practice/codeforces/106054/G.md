 ## 解决方案
 ## 问题理解

 我们正在建模一个非常小的支付系统。 一位顾客想要购买一件商品，价格为$A$比索。 他用一张账单支付$B$比索，因此信息亭必须准确返回$B - A$比索的变化。 不同的是，售货机不返回硬币或纸币，只返回糖果，并且每种糖果都有固定的价值$C$比索。 

问题是是否可以仅使用完整的有价值的糖果来表示准确的找零金额$C$。 换句话说，我们需要判断差异是否存在$B - A$可以写成$k \cdot C$对于某个整数$k \ge 0$。 

约束非常小，所有值最大为 1000。这立即消除了对性能或溢出的任何担忧，因为即使是直接算术检查也是恒定时间。 

一个微妙的问题是理解“精确变化”的要求。 亭子靠近还不够。 任何剩余或不足都会使解决方案失效。 例如，如果$A = 6$,$B = 10$， 和$C = 3$，变化是 4。两颗糖果给 6，太多了，一颗糖果给了 3，太少了。 这是一个直接的例子，即使值很小，整除性也会失败。 

边缘情况主要是关于可分性逻辑而不是计算。 自从$A < B$，变化总是积极的，所以我们永远不需要处理零或消极的变化。 这消除了解释中唯一潜在的歧义。 

## 方法

 思考这个问题的蛮力方法是尝试所有可能数量的糖果。 如果我们选择$k$糖果，我们回馈$k \cdot C$比索。 我们可以迭代$k$从 0 到$\lfloor (B-A)/C \rfloor$并检查任何选择是否与所需的更改完全匹配。 

这是正确的，因为唯一有效的交易是整数倍$C$。 然而，即使这里的范围足够小，这种方法在结构上也是低效且不必要的。 在问题的更大变体中，迭代所有$k$将与变化量的大小成线性关系。 

关键的观察是我们并不是在寻找任何不可分割的特殊结构。 我们只是检查是否存在差异$B - A$可以整除$C$。 如果是，那么我们可以用糖果来形成精确的零钱； 如果没有，那是不可能的。 

这将整个问题简化为单个模运算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(B-A)$|$O(1)$| 已接受但没有必要 |
 | 最佳 |$O(1)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 计算变化量$D = B - A$。 这代表信息亭必须返回的确切值。 
2. 检查是否$D$可以整除$C$，意思是是否$D \bmod C = 0$。 如果这个成立，则可以使用糖果来准确地形成变化。 
3. 如果满足整除条件，则输出“S”，否则输出“N”。 

这个检查足够的原因是每个糖果的贡献是准确的$C$比索，除了非负数之外，对糖果的数量没有任何限制。 

### 为什么它有效

 任何有效的解决方案都必须将变化表示为相同大小单位的总和$C$。 这意味着更改必须位于集合中$\{0, C, 2C, 3C, \dots\}$。 这个集合恰好是 的倍数的集合$C$。 该集合中的成员资格相当于除以时余数为零$C$。 自从$D = B - A$是固定的和确定性的，检查整除性充分表征了可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

A, B, C = map(int, input().split())

change = B - A

if change % C == 0:
    print("S")
else:
    print("N")
```该解决方案读取三个整数，计算所需的更改，并应用模检查。 关键的实现细节是首先计算差异，然后再应用模，这可以保持逻辑清晰并避免对多个表达式进行推理。 

不需要循环或边缘情况分支，因为有效答案的结构纯粹是算术。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline
    A, B, C = map(int, input().split())
    change = B - A
    return "S" if change % C == 0 else "N"

# provided samples
assert run("10 20 5") == "S"
assert run("6 10 3") == "N"

# custom cases
assert run("1 2 1") == "S"   # exact 1 candy
assert run("1 3 2") == "S"   # 2 change with 1 candy
assert run("1 4 2") == "S"   # multiple candies exact fit
assert run("1 5 2") == "N"   # remainder case
assert run("999 1000 7") == "N"  # small edge non-divisible
```| 测试输入| 预期产出 | 它验证了什么 |

 ## 边缘情况

 一种边缘情况是变化恰好等于一颗糖果的值。 用于输入`A = 1, B = 4, C = 3`，变化为 3。算法计算$3 \bmod 3 = 0$，所以它正确输出“S”。 这相当于只给出一颗糖果。 

另一种极端情况是零钱比糖果还小。 用于输入`A = 6, B = 10, C = 7`，变化为 4。由于 4 不能被 7 整除，所以模检查失败，输出为“N”。 这说明了使用较大的固定单位来表示较小的金额是不可能的。 

最后的边缘情况是当变化为零时，这在约束下实际上不会发生$A < B$。 如果允许，该算法仍然可以正确工作，因为零可以被任何正数整除$C$，产生“S”，符合不给糖果有效的事实。
