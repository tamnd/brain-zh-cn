 ## 解决方案

 ## 问题理解

 我们在数轴上得到一组点。 每个点都从某个整数位置开始，并在时间上永远移动，每个点都有自己的恒定速度。 如果我们选择任意两点，它们的距离会随着时间而变化，因为它们的位置线性变化。 

对于一对固定的点，我们对它们在特定时刻的距离不感兴趣，而是对它们在任何实时达到的最小距离感兴趣。 如果两点相遇，则最小距离变为零。 否则，它们会相互接近直到某个时刻，然后再次分开，并且最小值出现在它们的相对距离最小的时刻。 

任务是计算每对的最小可能距离并对它们进行求和。 

这些约束最多允许 200,000 个点，这会立即排除任何显式检查所有对或模拟随时间变化的交互的方法。 在最坏的情况下，二次解将涉及约 400 亿对，这远远超出了两秒内的可行极限。 这促使我们采用一种方法，其中每个点以结构化的方式对许多对做出贡献，通常使用排序和前缀处理。 

当天真的思考运动时，就会出现一个微妙的问题。 模拟碰撞或按初始位置排序并尝试进行本地推理很诱人，但最小距离同时取决于位置和速度。 如果后一个点更快，最初相距很远的两个点可能会稍后相遇，如果前一个点更快，两个接近的点可能永远不会相遇。 

一些边缘案例揭示了天真的推理失败的原因。 考虑速度相等的两个点。 它们永远不会改变相对距离，因此最小值只是它们的初始间隙。 如果我们错误地假设他们可能会随着时间的推移见面或重新排序，我们就会错误地将他们的贡献设置为零。 

另一种情况是较快的点在较慢的点之前开始。 它们立即发散，因此最小值又是初始距离。 任何假设更快的点总是“赶上”的逻辑在这里都会失败。 

最后，当较快的点在较慢的点后面开始时，它们可能恰好相遇一次，并且最小距离变为零。 有效捕获这种行为是核心难点。 

## 方法

 暴力解决方案独立检查每对点。 对于每一对，我们计算它们的距离最小化的时间。 时间 t 时 i 点和 j 点之间的距离为：

 |x_i - x_j + t(v_i - v_j)|

 这是 t 的 V 形函数，最小值出现在 t = 0 时或当它们满足时表达式变为零时。 我们可以推导出速度不同时的相遇时间并进行相应的评估。 

但是，计算所有对的此值需要 O(n^2) 运算。 当 n = 200,000 时，这是完全不可行的。 

关键的观察是我们实际上不需要明确地跟踪时间。 两个移动点之间的最小距离仅取决于它们的相对运动是否将它们带到一起。 如果我们按位置对点进行排序，我们可以将点对分为速度顺序“对齐”的点对和速度顺序“相反”的点对。 

对于任何 x_i < x_j 的对 (i, j)，定义相对速度 v_i 和 v_j。 如果 v_i <= v_j，则左侧点没有捕获右侧点，因此距离只会增加或保持不变。 最小值就是 x_j - x_i。 

如果 v_i > v_j，左边的点更快并且最终会赶上，这意味着距离在某个时刻减小到零，因此贡献为零。 

因此，问题简化为对所有对的初始距离求和减去那些“捕获对”（其中 v_i > v_j）。 我们需要一种有效的方法来计算和累积这些贡献。

这成为一个经典的反转式聚合问题：我们处理按位置排序的点，并维护一个速度数据结构，使我们能够计算有多少先前的点具有更大或更小的速度，并有效地累积位置差异。 

速度的芬威克树与位置的前缀和相结合，使我们能够计算每个点对数时间的贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最优（Fenwick + 排序）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们首先按点的初始位置对点进行排序。 这确保了每对都按固定的从左到右的顺序考虑，因此我们可以一致地解释贡献。 

然后，我们从左到右处理点，维持先前看到的点的速度结构。 

1. 按位置 x 对所有点进行排序。 

排序修复了顺序，以便对于任何对 (i, j)，在扫描中 i 始终位于 j 的左侧。 
2. 维护一棵 Fenwick 树，跟踪我们为每个速度值看到的点数量以及它们的位置总和。 

我们压缩速度以处理大范围。 
3. 对于按位置递增顺序排列的每个点 j，我们计算对所有先前点 i < j 的贡献。 

如果不存在运动，则基线贡献是总距离：

 x_j * count_left - sum_left_positions。 
4. 在这些对中，我们减去左侧点赶上的情况 (v_i > v_j)。 

使用 Fenwick 树，我们查询之前有多少个点的速度大于 v_j 并相应地调整贡献。 
5. 处理完j点后，我们将其插入到Fenwick结构中。 

关键的一点是，所有成对的贡献都可以分解为位置的前缀和和按速度阈值分割的计数。 

### 为什么它有效

 固定点 j。 所有先前的点 i 形成对 (i, j)。 由于位置已排序，因此 x_i < x_j 始终成立。 对于每个这样的对，最小距离为 x_j - x_i（如果它们从未相遇）或 0（如果 i 捕获 j）。 

满足条件是v_i > v_j。 因此，在所有前面的点中，我们只需要通过相对于 v_j 的速度将它们分开。 一旦知道了这个划分，就可以确定每个贡献，而无需模拟时间。 

Fenwick 树以增量方式准确维护此分区信息，确保每个查询反映正确的交互点集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    n = int(input())
    x = list(map(int, input().split()))
    v = list(map(int, input().split()))

    pts = list(zip(x, v))
    pts.sort()

    vals = sorted(set(v))
    comp = {val: i + 1 for i, val in enumerate(vals)}

    fw_cnt = Fenwick(len(vals))
    fw_sum = Fenwick(len(vals))

    total = 0

    sum_x = 0
    cnt = 0

    for xi, vi in pts:
        idx = comp[vi]

        left_sum = sum_x
        left_cnt = cnt

        total += xi * left_cnt - left_sum

        cnt_leq = fw_cnt.sum(idx)
        sum_leq = fw_sum.sum(idx)

        cnt_gt = cnt - cnt_leq
        sum_gt = sum_x - sum_leq

        total -= cnt_gt * xi - sum_gt

        fw_cnt.add(idx, 1)
        fw_sum.add(idx, xi)

        sum_x += xi
        cnt += 1

    print(total)

if __name__ == "__main__":
    solve()
```该解决方案是围绕一次从左到右的扫描构建的。 变量`sum_x`和`cnt`维护位置上的前缀信息，允许快速计算假设没有相遇的总成对距离。 

芬威克树按相对于当前点的速度分割先前的点，让我们精确地减去那些运动导致合并的点对。 

一个常见的错误是忘记这两种贡献都取决于头寸总和，而不仅仅是计数。 另一个是在处理当前点后更新 Fenwick 结构，因为太早包含它会破坏严格的从左到右的分区。

 ## 边缘情况

 一个关键的边缘情况是所有速度都相等。 在这种情况下，没有一对会改变相对距离，因此答案只是所有成对位置差异的总和。 该算法可以正确处理此问题，因为芬威克树从不识别任何“捕获”对，因此不会发生减法。 

另一个边缘情况是在增加的位置顺序中严格降低速度。 每个左边的点都比所有右边的点都快，所以每一对都会相遇。 正确答案是零，算法实现了这一点，因为每对都被分类到捕获组并完全减去。 

第三种边缘情况是交替速度，其中一些对相遇而另一些对不相遇。 芬威克树中基于速度的分裂结构确保每对都根据相对速度独立分类，因此处理混合行为时不会对之间产生干扰。
