 ## 解决方案

 ## 问题理解

 我们得到三个按非递减顺序排列的正整数。 将它们视为数轴上的三个旋钮。 在一次移动中，我们可以将任何单个旋钮向左或向右移动一个单位，但不允许将旋钮推到 1 以下。目标是将三元组重塑为新的有序三元组，以便中间值是第一个值的倍数，最后一个值是中间值的倍数。 

输出不仅是达到这种配置所需的最小移动次数，而且是实现这一最小值的具体最终配置。 

关键的困难在于我们想要的结构非常严格：一旦最小值固定，中间值就被迫是它的某个倍数，而最大值则被迫是中间值的倍数。 这使得有效三元组的空间在密集的整数网格内变得稀疏。 

约束足够小，可以直接搜索所有可能的最终三元组。 每个值最多为 10^4，因此如果我们控制搜索空间，即使候选值的嵌套迭代也是可以接受的。 试图在没有结构的情况下天真地构建所有可能的三元组的解决方案仍然会通过，因为域是紧密绑定的。 

当最佳解决方案将值折叠在一起时，例如将所有三个数字变成相同的值，就会出现微妙的边缘情况。 例如，转动`100 100 101`进入`100 100 100`是最优的，但任何只考虑严格增加三元组的方法都可能会错过它。 另一个特殊情况是减少值比增加值更便宜，当我们允许折叠到更小的除数（例如 1）时，通常会发生这种情况。 

## 方法

 蛮力方法始于我们可以尝试所有可能的最终三元组的想法$A \le B \le C$。 对于每个选择，我们将成本计算为绝对差之和$|a-A| + |b-B| + |c-C|$，但我们只让三元组满足$B \bmod A = 0$和$C \bmod B = 0$。 

这是正确的，因为每个有效的目标配置都经过显式测试，并且成本函数与所需的移动次数完全匹配。 问题在于候选人的数量。 每个变量最多可以达到 10^4 左右，因此完整的搜索空间约为$10^{12}$，这是不可能的。 

关键的观察是有效三元组的结构是分层的。 一旦我们选择了$A$，唯一有意义的选择$B$是的倍数$A$，一旦我们选择$B$，唯一有意义的选择$C$是的倍数$B$。 这极大地减少了搜索空间，因为每一步都会将分支因子从任意整数缩小到受算术级数约束的除数。 

我们不是尝试所有三元组，而是尝试所有可能的候选者$A$，那么对于每个$A$, 枚举倍数$B$，并且对于每个$B$, 枚举倍数$C$。 由于在实践中，对于最佳班次，值的范围大约为 2 × 10^4，因此该枚举仍然很小。 

我们还依赖第二个关键思想：最优解决方案往往接近原始值。 因此我们只需要考虑附近的候选者$a$,$b$， 和$c$，通常在一个小的有界窗口内，因为远距离移动总是比调整附近的有效配置更昂贵。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) 超过 10⁴ 域 | O(1) | O(1) | 太慢了|
 | 具有有界搜索的除数枚举 | 最坏情况为 O(n √n)，实际中要小得多 | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们通过锚定第一个元素并向上构建有效的链来迭代可能的最终值。 

1. 确定一个候选值$A$在原始值周围的范围内$a$，通常从 1 到一个小范围，例如 2 × 10^4。 我们这样做是因为最优解不能任意偏离原始值而不产生不必要的成本。 
2. 对于每个$A$, 选择一个候选人$B$作为$A$。 我们通过迭代乘法器来生成这些$k$这样$B = kA$。 这保证了可分性约束$B \bmod A = 0$。 
3. 对于每个$B$, 选择一个候选人$C$作为$B$，再次迭代乘法器$m$这样$C = mB$。 这强制执行$C \bmod B = 0$。 
4. 对于每个有效的三元组$(A, B, C)$，计算总成本为$|a - A| + |b - B| + |c - C|$。 我们跟踪迄今为止看到的最低成本。 
5. 存储达到该最小值的三元组。 

这样做的原因是每个有效的最终配置都必须满足严格的可分链。 通过通过乘法而不是任意选择来构造候选者，我们准确地生成了可行的集合，而不会丢失任何有效的结构。 

搜索空间很小，因为一旦$A$的倍数是固定的$A$低于界限是有限的，同样对于$B$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXV = 20000

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c = map(int, input().split())

        best = 10**18
        best_triple = (a, b, c)

        # Try A
        for A in range(1, MAXV + 1):
            # Try B as multiple of A
            for B in range(A, MAXV + 1, A):
                # Try C as multiple of B
                for C in range(B, MAXV + 1, B):
                    cost = abs(a - A) + abs(b - B) + abs(c - C)
                    if cost < best:
                        best = cost
                        best_triple = (A, B, C)

        print(best)
        print(*best_triple)

if __name__ == "__main__":
    solve()
```实现的核心是三层循环结构，通过构造强制可分性。 我们只生成有效的三元组，而不是在生成三元组后检查条件。 

常数`MAXV`选择足够大以轻松覆盖所有有用的候选者。 增加它不会改变正确性，只会改变运行时间。 

一个常见的错误是忘记 C 必须作为 B 的倍数而不是作为自变量进行迭代。 另一个错误是允许对倍数进行非整数步进，这会破坏整除性保证。 

## 工作示例

 我们追踪两个案例。 

### 示例 1：`1 2 3`我们从小值开始探索候选链。 

| 一个 | 乙| C | 成本 = |1-A| + |2-B| + |3-C| |

 |---|---|---|---|

 | 1 | 1 | 1 | 3 |

 | 1 | 1 | 2 | 2 |

 | 1 | 1 | 3 | 1 |

 | 1 | 2 | 2 | 1 |

 | 1 | 2 | 4 | 3 |

 最佳值在 (1, 2, 2) 或 (1, 1, 3) 处实现，两者在取决于可分链解释的约束下有效，并且最小成本为 1。 

这表明最佳解决方案可能不会严格通过接近原始值来保留排序结构，而是通过平衡所有三个坐标的成本来保留排序结构。 

### 示例 2：`100 100 101`我们评估附近崩溃的解决方案。 

| 一个 | 乙| C | 成本|
 | ---| ---| ---| ---|
 | 100 | 100 100 | 100 100 | 100 1 |
 | 100 | 100 100 | 100 200 | 200 99 | 99
 | 101 | 101 101 | 101 101 | 101 3 |

 最好的选择是折叠到 (100, 100, 100)，确认仅减少一个坐标通常比移动所有三个坐标更便宜。 

这条轨迹表明了为什么允许向下移动是至关重要的。

 ## 边缘情况

 一个关键的边缘情况是所有三个数字都应该折叠到相同的值。 对于像这样的输入`100 100 101`，算法考虑链，其中$A = B = C = 100$，产生成本 1。仅向下调整最大值的贪婪方法可能会错误地尝试通过增加中间值来匹配整除性，从而导致更高的成本。 

另一种边缘情况是当最佳配置涉及显着缩小值时，例如`1 22 29`。 在这里，转向像这样的小除数结构`(1, 22, 22)`比尝试向上对齐要便宜。 该算法正确地探索了这些，因为它枚举了从小到大开始的所有可分链$A$，确保始终考虑崩溃的解决方案。
