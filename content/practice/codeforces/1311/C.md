 ## 解决方案
 ## 问题理解

 我们给定一个固定的字符串`s`它代表格斗游戏组合中的一系列按钮按下操作。 玩家反复尝试从左到右键入整个字符串。 

然而，该过程被中断。 第一次期间`m`尝试，每次尝试仅在某个位置成功`p_i`，之后播放器立即从头开始。 在最后一次尝试中，玩家不间断地成功完成了整个字符串。 

因此，实际的按下顺序不仅仅是`s`重复多次。 相反，它是前缀的串联`s`由失败的尝试确定，然后是一份完整的副本`s`。 任务是计算每个字母出现了多少次`a`到`z`在这整个过程中都受到压力。 

关键的困难在于尝试的总数和字符串长度都可能很大，最多可达`2 * 10^5`测试用例的总和。 每次尝试都附加子字符串的直接模拟会太慢，因为它可能会重复扫描字符串的前缀，从而在最坏的情况下导致二次行为。 

天真的错误通常来自于独立处理每个失败的尝试并仅计算前缀`s[0:p_i]`没有意识到重叠的前缀会累积频率贡献。 另一个微妙的问题是忘记包含最终成功的字符串完整遍历。 

例如，如果`s = "abc"`和`p = [1, 1, 2]`，正确的顺序包括`"a" + "a" + "ab" + "abc"`。 幼稚的方法可能会错误地重新计算或覆盖贡献而不是累积它们，从而导致不正确的频率。 

## 方法

 暴力模拟将通过迭代前缀长度来处理每次尝试`p_i`并递增该前缀中每个字符的计数。 处理完所有失败的尝试后，我们将再次处理完整的字符串。 

这是正确的，因为它准确地反映了实际过程。 然而，其复杂性是有问题的。 每个`m`尝试可能需要最多`O(n)`在最坏的情况下工作，并且由于总和`n`和`m`可以达到`2 * 10^5`，最坏情况总体操作方法`O(nm)`在单个测试或跨案例中，这太慢了。 

关键的观察是我们永远不需要显式地重建字符串。 相反，我们只需要知道在所有失败的尝试中每个前缀位置被访问了多少次。 如果我们知道索引的频率`i`包含在前缀中，我们可以直接累积贡献。 

这将问题转化为前缀范围上的频率累积问题。 我们维护一个数组`cnt[i]`代表多少次位置`i`包含在失败的尝试中。 每次失败的尝试都会为所有指数贡献 +1`1..p_i`。 这可以使用差异数组有效地处理。 处理完所有查询后，我们计算前缀和`cnt`了解在最终运行之前每个位置被访问了多少次。 

最后，我们为整个字符串中的每个字符添加一次，以实现最终的成功尝试。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(纳米) | O(1) 额外 | 太慢了|
 | 最佳 | O(n + m) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，读取字符串`s`和前缀长度列表`p`。 

目标是计算每个位置出现了多少次`s`在最后一次完整尝试之前被访问。 
2. 创建一个整数数组`cnt`尺寸的`n + 1`，初始化为零。 

该数组将存储每个索引被失败尝试覆盖的次数的差异表示。 
3. 对于每个值`p_i`, 增量`cnt[0]`加 1 并减`cnt[p_i]`1.

 这编码了所有位置`0`到`p_i - 1`受到这次失败尝试的影响。 差异数组避免显式迭代前缀。 
4. 转换`cnt`使用前缀总和转化为实际覆盖率计数。 

这一步之后，`cnt[i]`表示包含位置在内的失败尝试次数`i`。 
5. 用零初始化大小为 26 的答案数组。 

这将存储每个字符的总频率。 
6. 对于每个位置`i`在字符串中，添加`cnt[i] + 1`到的频率`s[i]`。 

这`+1`说明最终成功的尝试，它总是遍历整个字符串一次。 
7. 输出26个累加值。 

### 为什么它有效

 每次失败的尝试都会为其前缀中的每个索引提供一次访问。 差异数组对这些区间贡献的总和进行编码，而无需显式地迭代它们。 前缀求和后，每个位置都确切地知道有多少次失败尝试包含它。 加一就是最后一次完整的遍历。 由于每个位置的贡献是相加且独立的，因此对每个索引求和会产生每个字符的正确总频率。

    import sys
    input = sys.stdin.readline

    def solve():
        t = int(input())
        for _ in range(t):
            n, m = map(int, input().split())
            s = input().strip()
            p = list(map(int, input().split()))

                cnt[0] += 1
                cnt[x] -= 1

            freq = [0] * 26

            print(*freq)

    solve()

 ## 边缘情况

 一种边缘情况是当所有`p_i = 1`，这意味着每次失败的尝试仅贡献第一个字符。 在这种情况下，差异数组在索引 0 处大量增加堆栈，而所有其他位置不受影响。 该算法仅多次正确累积第一个字符加上一次完整遍历。 

另一个边缘情况是当所有`p_i = n - 1`，这意味着每次失败的尝试几乎都完成了字符串。 在这里，每个索引都被大量覆盖，并且前缀和确保整个字符串的均匀贡献。 决赛`+1`正确地添加了一个额外的完整通道。
