 ## 解决方案
 ## 问题理解

 该问题描述了从左到右处理的一系列任务。 每个任务都有奖励值和体力减少百分比。 你一开始的耐力等于1。如果你完成了一个任务，你获得的奖励等于任务值乘以你当前的耐力，然后你的耐力会减少给定的百分比。 如果你跳过任务，你将一无所获，你的体力也保持不变。 目标是选择完成哪些任务，以使最终的总奖励尽可能大。 

输入包含多个测试用例。 对于每个测试用例，第一个值是任务数。 以下每一对描述一个任务：第一个数字是其奖励系数，第二个数字是完成该任务后耐力损失的百分比。 输出是可达到的最高分数。 

所有测试用例的任务总数足够大，以至于不可能检查所有子集。 如果有多达 100000 个任务，则暴力方法将需要考虑指数数量的选择，大约$2^{100000}$，无法处理。 即使具有太多状态的动态程序也会失败，因此解决方案必须以恒定的次数处理每个任务。 

棘手的情况来自于这样的理解：耐力仅在任务完成时才会改变，而一项任务的决定取决于未来的任务。 总是获取最大即时奖励的贪婪方法可能会失败，因为早期任务可能会降低耐力并使后续任务的价值大大降低。 

例如：```
1
10 100
```答案是`10`。 粗心的实施可能会将奖励乘以减少后的体力而得到零，但奖励是在体力变化之前获得的。 

另一个例子：```
3
10 5
10 80
20 5
```最好的答案是`29`。 完成所有任务给出：```
10 + 9.5 + 17.1 = 36.6
```实际上这个例子说明了为什么顺序很重要，因为第二个任务破坏了大部分的耐力。 最佳选择是跳过中间任务：```
10 + 20 * 0.95 = 29
```仅比较单个任务奖励的解决方案忽略了耐力作为所有未来已完成任务的乘数的效果。 

## 方法

 直接的强力解决方案将尝试任务的每个子集。 对于每个子集，我们按顺序模拟所选任务，保持当前的耐力和累积分数。 这是正确的，因为每个可能的决策序列都会被检查。 然而，每增加一个任务，子集的数量就会加倍，因此对于 100000 个任务，可能性的数量远远超出了任何计算机可以处理的范围。 

有用的观察是，当我们从列表末尾查看任务时，未来已经被总结了。 假设我们知道当前任务之后的所有任务可获得的最高分数，假设我们当前的耐力为 1。如果我们决定完成当前任务，我们会立即获得其奖励，然后所有未来的奖励都会根据剩余的耐力进行调整。 如果我们跳过它，我们只需保持未来值不变。 

这给出了一维动态规划状态。 让`dp`代表从当前正在考虑的任务后缀中获得的最佳分数，其中耐力因素被分离出来。 当处理有奖励的任务时`c`和剩余体力倍数`m`，完成它给出：$$c + m \times dp$$对于此问题，完成任务后的耐力倍数为：$$1 - \frac{p}{100}$$因此，当从末尾移动到开头时，过渡变为：$$dp_i = \max(dp_{i+1}, c_i + (1-\frac{p_i}{100})dp_{i+1})$$这样做的原因是当前任务对未来的唯一影响是应用于未来奖励的单个乘数。 我们不需要记住之前选择的整个历史。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(2^n \cdot n)$|$O(1)$| 太慢了|
 | 最优动态规划|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 读取任务并从最后一个任务到第一个任务进行处理。 当后缀答案已知时，未来的决策就更容易描述。 
2. 维护一个变量`dp`包含在此反向遍历中迄今为止处理的任务中可获得的最大分数。 最初没有未来的任务，所以`dp = 0`。 
3.当前任务有奖励`c`和耐力损失百分比`p`，完成后计算结果。 获得的奖励为`c`，并且每个未来的奖励都乘以`1 - p / 100`。 
4. 将完成任务的价值与跳过任务的价值进行比较。 保留较大的值作为新的`dp`。 
5. 处理完所有任务后，`dp`是整个序列的答案。 

为什么它有效：动态编程不变式是在以相反顺序处理任务之前，`dp`等于当当前耐力因素被视为 1 时，该任务之后所有任务可能获得的最佳分数。 对于当前任务，每个有效策略要么跳过它，要么完成它。 该转换准确地评估了两种可能性，并且不需要来自早期任务的其他信息，因为耐力变化仅由应用于未来奖励的乘数来表示。 由于每个后缀在向左移动之前都已得到最佳解决，因此最终值对于整个任务列表都是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        tasks = []

        for _ in range(n):
            c, p = map(int, input().split())
            tasks.append((c, p))

        dp = 0.0

        for c, p in reversed(tasks):
            multiplier = 1.0 - p / 100.0
            take = c + multiplier * dp
            skip = dp
            dp = max(take, skip)

        ans.append(f"{dp:.10f}")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```输入被正常读取，因为任务总数是有界的，但是`sys.stdin.readline`避免不必要的开销。 

存储任务列表是因为转换需要从末尾运行到开头。 在向后处理的同时，`dp`仅存储已处理后缀的最佳值，因此不需要完整的动态编程数组。 

计算使用浮点数，因为耐力减少涉及百分比。 Python 整数没有溢出问题，但小数奖励需要浮点精度。 在小数点后打印十位数字足以满足所需的误差容限。 

操作顺序很重要。 奖励`c`在应用耐力乘数之前添加，因为完成任务会立即获得积分，然后会减少后续任务的耐力。

 考虑：```

3

 | 当前任务 | 当前 dp | 完整价值| 跳过值| 新 dp |

 ## 边缘情况

 对于这个案例：```
1
1
10 100
```该算法开始于`dp = 0`。 完成任务给出`10 + 0 * 0 = 10`，同时跳过给出`0`，所以答案变成10。体力减少发生在获得奖励后，不影响当前任务。 

对于这个案例：```
1
3
10 5
10 80
20 5
```逆向动态规划从最后一个任务开始。 最后一个任务之后的值是 20。中间的任务只会产生`10 + 0.2 * 20 = 14`，因此算法通过跳过它来保留 20。 第一个任务给出`10 + 0.95 * 20 = 29`，这成为最终答案。 

对于每次减少为零的任务：```
1
4
5 0
5 0
5 0
5 0
```每个完成的任务都会保持相同的耐力倍数。 过渡总是更喜欢接受任务，因为它会增加积极的奖励而不损害未来的奖励。 最终答案是20。
