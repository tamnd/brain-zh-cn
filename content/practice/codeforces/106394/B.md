 ## 解决方案
 # 问题理解

 爱丽丝发现一个房间，里面有`n`胸部。 每个箱子都有一个价值写在`a[i]`。 正值意味着打开该箱子会给爱丽丝硬币，而负值意味着箱子包含被诅咒的硬币并减少她的总数。 爱丽丝完全拥有`k`钥匙，这样她最多可以打开`k`胸部。 她的目标是选择要打开的箱子，以便她的最终硬币数量尽可能多。 

输入包含多个独立的测试用例。 对于每种情况，我们都会收到箱子的数量、可用钥匙的数量以及每个箱子的价值。 输出是Alice做出最佳选择后可能的最大余额。 

约束是主要线索。 所有测试用例的箱子总数可以达到`2 * 10^5`，因此尝试每个箱子子集的解决方案是不可能的。 甚至检查所有选择`k`箱子将呈指数级增长。 接近线性或的解`O(n log n)`每个测试用例都是必需的。 

关键边缘情况来自这样一个事实：Alice 不必使用每个密钥。 粗心的实现可能会假设她必须始终准确打开`k`胸部。 

例如：```
Input
1
3 2
5 -10 -20

Output
5
```爱丽丝有两把钥匙，但打开任何被诅咒的箱子都会降低她的结果。 正确的选择是只打开值得的宝箱`5`。 盲目选择两个箱子的解决方案会产生较小的值。 

另一种情况是每个箱子都被诅咒时：```
Input
1
4 3
-1 -2 -3 -4

Output
0
```爱丽丝从零硬币开始，可以简单地避免使用她的密钥。 对值进行排序并始终取第一个`k`不检查符号的元素会错误地得出否定的答案。 

## 方法

 直接的暴力方法会尝试爱丽丝可以打开的所有可能的箱子组，计算其总价值，并保留最大值。 这是正确的，因为每一个可能的决定都会被检查。 然而，子集的数量是`2^n`，即使是几十个箱子也是不可能的。 和`n = 2 * 10^5`，这种方法远远超出了可用时间。 

看待问题的更好方法是关注对答案有贡献的因素。 打开具有正值的宝箱会增加最终余额。 打开负值的箱子会减少它。 由于不需要花费所有密钥，因此负值无济于事。 

唯一有用的操作是选择最大的正值。 如果少于`k`正面的箱子，爱丽丝把它们全部拿走了。 如果有超过`k`，她应该保留最好的`k`正值，因为花费在较小值上的每个密钥都会阻止获得更大的奖励。 

这一观察结果将问题转化为排序问题。 我们收集所有正值，从大到小排序，最多相加`k`其中。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 排序步骤主导了运行时间。 该算法的其余部分仅扫描数组并对所选值求和。 

## 算法演练

 1.读取测试用例的数量并独立处理每个测试用例。 
2. 检查每个宝箱值并仅保留大于零的值。 这是唯一可以提高爱丽丝平衡能力的箱子。 
3. 将剩余的正值按降序排列。 排序后的第一个元素是最有利可图的选择。 
4.添加第一个`k`此排序列表中的值，或所有可用值（如果少于）`k`。 
5. 打印结果总和。 

这种贪婪选择起作用的原因是每个选定的箱子都会消耗一把钥匙。 如果解决方案包含较小的正值宝箱，而未选择较大的正值宝箱，则交换它们会增加或保持总数不变。 重复此交换仅留下选定的最大正值。 

为什么有效：该算法保持了不变性，即在考虑可用的正箱子后，所选值始终是所使用的密钥的最高可能奖励。 负值宝箱只会减少总数，因此移除它们不会有什么坏处。 最终选择的集合正是具有最大可能总和的集合。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        positive = [x for x in a if x > 0]
        positive.sort(reverse=True)

        ans.append(str(sum(positive[:k])))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```列表理解过滤掉所有被诅咒的箱子，因为负值永远不可能成为最佳解决方案的一部分。 该排序将最高奖励放在第一位，这与算法部分的贪婪推理相匹配。 

切片`positive[:k]`也是防止使用比 Alice 拥有的更多密钥的边界条件。 如果少于`k`有利可图的箱子存在，Python 会自动返回整个列表。 

求和使用Python整数，因此即使累加值超过32位或64位范围，也不存在溢出风险。

 ## 边缘情况

 当所有箱子都被诅咒时，正面列表就会变空。 为了：```
Input
1
4 3
-1 -2 -3 -4
```该算法在过滤过程中删除每个值。 排序不执行任何操作，所选值的总和为`0`，这与 Alice 不选择箱子相匹配。 

当正箱子比钥匙少时：```
Input
1
5 4
6 -2 3 -8 1
```过滤后的列表是`[6, 3, 1]`。 排序后剩下`[6, 3, 1]`，并且取前四个元素只需取所有三个值。 答案是`10`。 

当箱子比钥匙更有利可图时：```
Input
1
5 2
9 7 5 3 1
```排序后的列表是`[9, 7, 5, 3, 1]`。 仅使用前两个值，给出`16`。 任何较小值的替换都会降低结果，因此贪婪的选择是最优的。
