 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并且允许我们使用受限交换操作重新排列元素。 限制是我们只能交换指数除以固定数字时具有相同余数的头寸$k$。 这将数组划分为$k$独立指数类别：头寸$i, i+k, i+2k,\dots$都属于同一类，可以通过反复交换自由交换价值。 

执行完后达到$k$这样的交换，然后我们选择任何块$k$最终数组中的连续元素并取它们的总和。 任务是使用允许的交换来排列数组，以便所选的连续块具有最大可能的总和。 

该操作的关键结构含义是元素不可全局排列。 每个职位类别都是独立发展的，因此我们不能随意将大值移动到任何地方。 相反，每个残基类模$k$行为就像一个可以在内部重新排列的小型多重集。 

限制很小：$n \le 100$和$t \le 600$。 这立即告诉我们，即使$O(n^2)$或者$O(n^3)$每个测试用例的解决方案都是安全的。 真正的挑战不是性能，而是正确建模交换所允许的内容。 

当人们假设完全排列自由时，就会出现一种微妙的失败情况。 例如，如果我们错误地认为我们可以对整个数组进行排序并选择最佳窗口，那么当存在大值但被锁定到不兼容的残差类时，我们就会得到错误的答案。 如果我们假设我们总是可以“带来最大的$k$元素在一起”而不考虑模约束，这会破坏像这样的情况$k=2$其中偶数和奇数索引是独立的池。 

正确的方法必须尊重最终选择的片段中的每个位置只能用来自特定残基类别的元素填充。 

## 方法

 蛮力视图会尝试所有选择长度的方法-$k$模拟所有允许的交换后的段。 由于交换允许在每个残差类内进行任意排列，因此这变成：枚举每个类内分配值的所有方法，然后尝试所有窗口。 这种组合会爆炸，因为即使每个类都很小，但最终窗口中类之间的耦合使得直接枚举变得不可行。 

关键的观察是每个模类内部的交换使该类完全可重新排序。 所以对于每个残基类别$r$，我们可以将其值视为可以任意分配给位置的多重集$r, r+k, r+2k,\dots$。 最终的数组不是任意的，但每个类可以独立选择如何排列自己。 

现在考虑任何长度的候选窗口$k$，从位置开始$s$。 该窗口从每个残基类中精确选取一个元素，因为逐步遍历连续索引会循环遍历残基模$k$。 所以位置$s+i$始终对应于残基类别$(s+i) \bmod k$。 

因此，每个窗口从每个类中选择一个元素，我们希望最大化这些所选代表的总和。 由于每个类都是可独立重新排序的，因此对于每个残基类，我们希望确保将最佳可能元素放置在参与某些最佳窗口的位置。 

我们没有尝试构建完整的排列，而是翻转视角：对于每个残基类，按降序对其值进行排序，因为我们总是希望在可能的情况下更早地使用更大的元素。 然后我们考虑每个可能的起始索引$s$，通过从与该窗口结构对齐的每个类中选取最大的可用未使用元素来计算最佳可实现的总和。 

因为$k \le n \le 100$，我们可以通过维护每个残基的排序桶并贪婪地测试每个窗口启动来直接模拟此分配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（模拟所有交换和排列）| 指数| O(n) | 太慢了|
 | 最优（按 mod 类别存储桶 + 贪婪窗口评估）| O(n^2 log n) | O(n^2 log n) | O(n) | 已接受 |

 ## 算法演练

 1. 将数组拆分为$k$基于索引模的组$k$。 每组包含所有可以自由交换价值的位置。 
2. 按降序对每个组进行排序，以便我们始终知道该类中哪些元素最有价值。 
3. 对于每个可能的起始索引$s$的长度-$k$窗口，计算最佳可实现总和。 
4. 计算起始于的窗口$s$，迭代$k$窗口中的位置。 
5. 对于每个位置$s+i$，确定其残基类别$r = (s+i) \bmod k$，并从组中取出下一个最大的未使用元素$r$。 
6. 对这些选定的元素求和以获得该窗口的分数。 
7. 跟踪所有起始位置的最大值。 

每个类中的贪婪选择之所以有效，是因为在一个类中，所有排列都是可以实现的。 因此，我们可以为窗口中最“有用”的事件分配较高的值。 

### 为什么它有效

 每个残基类形成一个独立的排列空间。 任何最终的排列都相当于选择每个类别的排列。 每个长度-$k$window 以固定的循环模式从每一类中精确选择一个元素。 因此，最大化任何窗口减少为在一致的分配策略下从每个类中选择最佳的可用元素。 排序可确保我们永远不会将大元素浪费在不太有用的位置（当它可以对候选窗口做出贡献时）。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        groups = [[] for _ in range(k)]
        for i, val in enumerate(a):
            groups[i % k].append(val)

        for g in groups:
            g.sort(reverse=True)

        # we will simulate assignment greedily for each possible window
        ans = 0

        for start in range(n - k + 1):
            used = [0] * k
            score = 0

            for i in range(k):
                r = (start + i) % k
                score += groups[r][used[r]]
                used[r] += 1

            ans = max(ans, score)

        print(ans)

if __name__ == "__main__":
    solve()
```该实现首先构建残差类，因为它们是真正的自由单位。 按降序对每个组进行排序可确保我们始终可以访问该类的最佳剩余元素。 

对于每个候选窗口，我们模拟按顺序从每个类中取出一个元素。 这`used`数组跟踪我们已经从每个残留类中消耗了多少元素，以便在不同窗口位置重复出现同一类时不会错误地重用值。 

所有起始位置的外循环确保我们考虑每个有效窗口。 自从$n \le 100$，这种二次扫描就足够了。

 ## 边缘情况

 当发生最小情况时$n = 1, k = 1$。 该算法创建一个包含单个值的残基类别。 排序不执行任何操作，唯一的窗口会简单地选择该元素，从而产生正确的输出。 

当所有元素相同时，每个残基类都包含重复值。 排序和贪婪选择仍然为每个窗口产生相同的总和，因此最大值在所有起点上都是稳定的。 该算法不会过度计数，因为每个类索引都是独立递增的。 

什么时候$k = n$，每个窗口都是整个数组。 每个残基类只包含一个元素，因此没有交换会改变任何有意义的事情。 该算法仅正确评估一个窗口并返回总和。
