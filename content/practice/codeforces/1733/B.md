 ## 解决方案
 ## 问题理解

 我们有一个非常具体的淘汰式锦标赛。 玩家按照从 1 到 n 的固定顺序到达。 第一场比赛是在玩家 1 和玩家 2 之间进行，然后该场比赛的获胜者将与玩家 3 进行比赛，然后获胜者将与玩家 4 进行比赛，依此类推，直到玩家 n。 这恰好产生 n 负 1 场比赛，并且每场比赛恰好产生一个获胜者。 

我们不知道实际的比赛结果，只知道锦标赛中的每个玩家的最终获胜次数为 x 或 y。 我们的任务是确定是否存在与该约束一致的有效比赛结果序列，如果存在，则输出每场比赛的有效获胜者序列。 

锦标赛的结构受到很大限制。 每个玩家要么在输掉一次后立即停止比赛，要么在他们是当前冠军的情况下继续连续赢得比赛。 这意味着每个玩家的胜利都对应于一个连续的时间段，而不是任意分散的胜利。 

约束很严格：测试用例的数量最多可达 100,000 个，所有测试的 n 总和最多为 200,000。 这立即排除了每个测试用例的任何二次构造或模拟。 任何解决方案总体上都必须是线性的或接近线性的。 

当 x 和 y 都很小但与锦标赛结构不一致时，就会出现微妙的边缘情况。 例如，如果所有玩家都声称在 n 大于 2 的锦标赛中获得零胜，这是不可能的，因为只有一名玩家必须赢得最后一场比赛，从而至少获得一场胜利。 类似地，如果 x 和 y 相对于 n 都很大，我们必须确保总获胜结构与有效链中玩家之间分布的 n 减 1 场比赛完全匹配。 

## 方法

 暴力方法会尝试模拟所有可能的锦标赛结果。 在每场比赛中，我们都可以选择当前的冠军或下一个选手，涵盖所有可能性。 这形成了深度为 n 减 1 的二元决策树，导致 2^(n-1) 种可能的结果。 即使 n = 40，这也是不可行的，这里 n 可以达到 100,000。 

关键的观察是锦标赛结构不是任意的。 这是一个单一的进化冠军，因此所有比赛都形成一个链条。 每个玩家要么在一段时间内成为冠军，要么根本没有获胜。 这意味着胜利分配是高度结构化的：只有一名玩家可以获得最大获胜次数，因为只有一名玩家可以在连续多场比赛中保持冠军。 

如果我们确定了最终的冠军，比如玩家 k，那么所有比赛都会根据比较或构建的结果被迫朝着确定的方向发展。 真正的见解是，可以构建序列，使 x 或 y 之一恰好对应于冠军的获胜次数，其余的必须与剩余玩家的分区一致。 

这将问题简化为检查我们是否可以将玩家分配到与胜利计数 x 和 y 相对应的两组，同时尊重只有一个玩家是全局冠军并在其出现在链中后累积所有胜利。 

我们尝试通过选择一种候选结构来构建有效的序列，其中一个值代表冠军细分市场，另一个值代表非冠军参与者。 如果这个结构不能与n-1的总胜利数相一致，那么答案是不可能的。

 ## 算法演练

 构建的关键在于确定我们是否可以确定锦标赛的方向，以便具有一个获胜值的玩家围绕单个主导冠军形成有效的前缀后缀分区。

1. 我们检查两种解释：假设 x 代表冠军方，y 代表非冠军方，反之亦然。 这是必要的，因为我们不知道哪个值对应于哪个结构角色。 
2. 对于选定的解释，我们尝试将玩家分配到一个链中，其中只有一个玩家充当最终的持久获胜者。 该玩家必须具有两个值中较大的一个，因为它参与了最多的连续获胜。 
3. 我们确定组之间所需的转换次数。 每次转换对应于一​​场比赛，其中获胜者从一个组更改为另一个组。 这些转换必须与链结构完全对齐。 
4. 我们通过从左到右模拟锦标赛来贪婪地构建序列，始终确保当前冠军所需的获胜次数不会过早超过。 如果在任何时候约束强制执行不可能的分配，我们就会中止此配置。 
5. 如果一种配置成功，我们将输出构建的获胜者序列。 否则，我们报告不可能。 

### 为什么它有效

 关键的不变量是锦标赛始终保留一个活跃的冠军，并且每场胜利都归因于链中的一个转变。 这意味着问题简化为控制每个玩家在被替换之前可以保持冠军身份的时间。 由于只有一名球员可以在多场比赛中延长连胜，因此整个结构崩溃为一个连续的统治部分。 确保 x 和 y 与该段的一致性可以保证全局正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build(n, a, b):
    # try both assignments
    for x, y in [(a, b), (b, a)]:
        # impossible quick checks
        if x == 0 and y == 0:
            continue
        
        # we assume one special champion with x wins
        # number of wins of champion in this structure is at most n-1
        if x > n - 1:
            continue
        
        # we try to place champion at position x+1 in chain intuition
        res = []
        ok = True
        
        # initial champion is player 1
        cur = 1
        
        # we want cur to win x times total
        remaining_x = x
        
        for i in range(2, n + 1):
            # if we still need champion wins, keep cur winning
            if remaining_x > 0:
                res.append(cur)
                remaining_x -= 1
            else:
                # switch winner to current player i
                res.append(i)
                cur = i
        
        # verify counts
        cnt = [0] * (n + 1)
        for w in res:
            cnt[w] += 1
        
        valid = True
        for i in range(1, n + 1):
            if cnt[i] not in (x, y):
                valid = False
                break
        
        if valid:
            return res
    
    return None

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, x, y = map(int, input().split())
        ans = build(n, x, y)
        if ans is None:
            out.append("-1")
        else:
            out.append(" ".join(map(str, ans)))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码尝试通过尝试对哪个值对应于主导角色的两种解释来构建有效的获胜者序列。 它模拟从左到右的比赛链，维持当前的冠军并在每一步决定冠军是继续还是被替换。 在构建了比赛获胜者的候选序列后，它会计算每个玩家的获胜次数，并验证每个玩家的获胜次数是否与 x 或 y 匹配。 

关键的微妙之处在于我们并没有提前假设一个固定的冠军。 相反，我们允许冠军的身份在构建过程中不断演变，这反映了真实的锦标赛过程。

 ## 边缘情况

 当 x 和 y 都为零时，就会出现临界边缘情况。 对于任何大于 2 的 n，这立即与恰好 n 负 1 场比赛产生获胜者的要求相矛盾，因此至少一名玩家必须具有正的获胜计数。 该算法在没有构造的情况下就提前拒绝了这一点。 

另一个边缘情况是当 x 等于 n 减 1 时。这迫使单个玩家赢得每场比赛，这意味着锦标赛是完全线性的，没有成功的替代者。 任何试图提前引入新冠军的构造都会违反胜利分布，因此算法必须始终保留初始冠军。 

当 x 和 y 接近时，就会出现第三种情况，例如 x = 3 且 y = 2，n = 6。这里，多个玩家必须交替成为冠军和挑战者。 贪婪的结构确保了当当前冠军的剩余所需胜利耗尽时，冠军切换会准确发生，从而防止过早或延迟的过渡，从而扭曲计数。
