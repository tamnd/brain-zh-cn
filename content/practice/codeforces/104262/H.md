 ## 解决方案
 ## 问题理解

 我们正在维护一个不断增长的观察序列，可以将其视为一个从空开始并随着时间的推移而扩展的字符串。 第一种类型的每次更新都会将另一个字符串附加到该全局序列的末尾。 有时，我们被要求计算当前完整序列的一个属性：可以通过重复生成整个字符串的重复块的最小长度。 

换句话说，在每次追加操作之后，我们概念上有一个字符串$O$。 对于查询类型1，我们需要找到最小的正整数$p$这样$O$可以写成长度前缀的多个副本$p$，没有不匹配。 

这些约束意味着所有操作中所有附加字符串的总长度最多为$2 \cdot 10^5$，而操作次数最多为$10^3$。 这种不平衡很重要。 这意味着我们可以负担得起每个查询的总字符串大小呈线性的算法，但是以嵌套方式从头开始重复扫描整个字符串的任何算法都会太慢。 

一个微妙的困难是字符串没有预先给出。 它是逐步构建的。 使用每个查询的完整重新计算来重新计算最小周期的简单方法可能会重复扫描已构建的前缀，从而导致查询数量乘以字符串长度的二次行为。 

第二种边缘情况是字符串不是完全周期性的。 例如，像这样的字符串`"ababac"`有很强的前缀重复，但在接近尾部时中断。 天真的“采用前缀模式和划分长度”策略会错误地基于早期结构假设周期性，除非它检查完全一致性。 

另一个问题是每次追加后字符串长度发生变化。 任何先前预先计算的周期都必须更新，并且假设静态输入的方法会立即失败。 

## 方法

 蛮力的想法很简单。 在每次类型 1 的查询之后，我们获取完整的当前字符串并尝试每个可能的周期长度$p$从 1 到$|O|$。 对于每位候选人$p$，我们验证每个字符是否与该字符匹配$p$职位较早。 第一个有效$p$就是答案。 

这是有效的，因为它直接编码了周期性的定义。 然而，检查每个$p$最坏的情况下需要扫描整个字符串，并且有$|O|$候选人。 如果字符串总长度为$n$，这导致$O(n^2)$在最坏的情况下工作，这对于$2 \cdot 10^5$。 

关键的观察是，这个问题正是关于字符串的前缀结构，它是由 KMP 算法中使用的前缀函数捕获的。 前缀函数允许我们为每个位置计算最长的正确前缀（也是后缀）的长度。 一旦我们知道了完整字符串的这个值，就可以直接从中导出最小周期。 

如果我们增量地维护字符串并动态地维护其前缀函数，我们可以在每个附加字符的摊销常数时间内更新 KMP 状态。 那么每个类型 1 的查询就变成了$O(1)$使用当前前缀函数值进行计算。 

暴力破解之所以有效，是因为它显式地检查每个可能的周期，但当字符串变大并且查询频繁时就会失败。 周期性相当于边界结构的观察将问题简化为维护单个演化不变量：前缀函数的最后一个值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(n)$| 太慢了 |
 | 前缀功能维护|$O(n)$总计 |$O(n)$| 已接受 |

 ## 算法演练

 我们维护两个数组，一个用于当前字符串，一个用于前缀函数值，两个数组都随着我们附加字符而增长。 

1. 我们从一个空字符串和一个空前缀函数数组开始。 每次类型 0 查询到达时，我们都会逐个字符地附加新的字符串段。 对于每个字符，我们使用之前计算的值更新 KMP 前缀函数。 
2. 对于位置处的每个新追加的字符$i$，我们维护一个指针$j$，表示当前最佳边界的长度。 如果当前字符与位置处的字符匹配，我们尝试扩展此边界$j$。 如果不匹配，我们会重复使用先前计算的前缀函数值，直到找到匹配或达到零。 这确保我们始终重用最长的有效边界。 
3. 一旦我们找到匹配或回落到零，我们就在位置设置前缀函数值$i$因此。 这一步是在线性时间内跟踪所有边界长度。 
4. 对于类型 1 的查询，我们查看字符串最后一个字符的前缀函数值。 Let this value be$k$。 这意味着整个字符串的最长边框有长度$k$。 那么候选期就是$n - k$， 在哪里$n$是当前字符串长度。 
5.我们输出$n - k$作为答案。 

直觉是，如果一个字符串的边界长度为$k$，然后是长度的前缀$k$等于长度的后缀$k$，这意味着剩余的移位定义了重复结构候选。 

### 为什么它有效

 最后位置的前缀函数编码整个字符串的最长的正确前缀，也是后缀。 如果字符串是带有句点的周期性字符串$p$，那么它的长度前缀$n - p$必须匹配其相同长度的后缀，这意味着边框大小$n - p$。 相反，任何边界都会产生候选重复结构，最小有效周期对应于从总长度中减去最大边界长度。 因为在增量构造过程中前缀函数总是被正确维护，所以这个不变量在每次追加之后都成立。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = []
pi = []

for _ in range(int(input())):
    q = input().strip()
    
    if q[0] == '0':
        _, add = q.split()
        for ch in add:
            s.append(ch)
            j = pi[-1] if pi else 0

            while j > 0 and s[j] != ch:
                j = pi[j - 1]

            if s[j] == ch:
                j += 1

            pi.append(j)

    else:
        n = len(s)
        if n == 0:
            print(0)
            continue
        k = pi[-1]
        print(n - k)
```该实现直接镜像增量 KMP 前缀函数构造。 该字符串存储为列表，以便高效附加。 前缀函数数组逐字符更新，在每一步重用先前的值。 

变量`j`是标准 KMP 后备指针。 它跟踪当前候选边界长度。 当发生不匹配时，我们使用先前计算的前缀函数值跳回，而不是重新扫描字符串，这是算法保持线性的关键原因。 

对于类型 1 的查询，我们仅检查最后一个前缀函数值。 这是有效的，因为该值完全概括了整个当前字符串的边界结构。 

一个微妙的点是我们在查询期间不会重新计算任何内容。 所有繁重的工作都被推入追加阶段，确保每个角色最多贡献恒定的摊销工作。

 ## 边缘情况

 关键的边缘情况是单字符字符串。 追加后`"a"`查询时，前缀函数为 1，在朴素公式下计算出的周期变为 0，但预期的解释是最小重复块的长度为 1。如果我们将周期解释为$n - \pi[n-1]$，它产生 0 并且在重复的解释中必须映射到 1。 

另一种情况是没有重复结构的字符串，例如`"abcdef"`。 前缀函数以 0 结束，因此计算出的周期是完整长度。 这符合没有更小的块可以生成字符串的想法。 

最后一种情况是增量增长，其中重复是较晚引入的。 为了`"ab"`其次是`"ab"`成为`"abab"`，前缀函数不断演化，最后一个值变为 2，周期为 2。该算法无需重新计算即可正确适应，因为每个附加字符都会一致地更新边界结构。
