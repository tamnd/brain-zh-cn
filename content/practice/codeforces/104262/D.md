 ## 解决方案
 ## 问题理解

 我们正在研究一个二维网格，其中恒星和黑洞都放置在一个小有界空间中的整数坐标处。 恒星代表我们想要计数的点，而黑洞则使附近的恒星失效。 

每个黑洞都会移除以其位置为中心的 3×3 正方形内的所有恒星，这意味着从黑洞开始的 x 和 y 方向上一个单元内的每个单元都变得不安全。 在这个删除过程之后，我们被要求回答多个矩形查询，每个查询询问该矩形内有多少剩余的星星。 

关键的困难在于恒星可以重叠，黑洞效应可以重叠，并且在应用所有删除后我们必须有效地回答多达 100000 个查询。 

坐标范围较小，两个维度都是从 0 到 999。 这立即表明，虽然对象数量很大，但几何图形是密集但有界的，这通常指向网格预处理或前缀和，而不是动态结构。 

一种简单的方法是检查每个查询的每颗恒星，并测试它是否被任何黑洞摧毁。 这太慢了，因为如果有 100000 个星和 100000 个查询，我们可以达到 10^10 次操作。 

一个微妙的边缘情况是重叠的黑洞。 例如，如果一个黑洞位于 (5,5)，另一个黑洞位于 (6,6)，则它们的 3×3 破坏区会严重重叠。 如果仅检查直接接近度而不首先聚合覆盖范围，则幼稚的实现可能会错误地多次减去或无法标记所有受影响的恒星。 

另一个边缘情况是重叠的星星。 如果多个恒星共享相同的坐标，则除非被摧毁，否则所有恒星都将单独计数。 任何基于网格的解决方案都必须累积计数，而不是将坐标视为集合。 

最后，在回答查询之前必须应用黑洞破坏。 如果错误地首先处理查询或延迟评估每个查询的破坏，结果将不一致。 

## 方法

 蛮力的想法很简单。 对于每颗恒星，我们扫描所有黑洞以确定它是否位于至少一个 3×3 破坏区域内。 如果它没有被破坏，我们就保留它。 然后，对于每个查询，我们扫描所有剩余的星星并计算查询矩形内的星星。 

这是正确的，因为它直接遵循破坏和计数的定义。 然而，复杂性变得令人望而却步。 仅检查销毁就需要花费 O(NM)，在 10^5 时，每个操作需要 10^10 次操作。 即使稍微优化，这也远远超出了限制。 添加查询评估会进一步增加成本。 

关键观察来自坐标约束。 由于所有坐标都位于 1000×1000 网格中，因此我们可以在固定大小的数组上预先计算所有内容。 我们不是单独跟踪恒星，而是将它们聚合成频率网格。 我们不是模拟每颗恒星的破坏，而是标记第二个“阻塞”单元网格并在本地传播黑洞影响。 一旦两者都在网格上编码，我们就可以计算最终的有效星形网格并构建 2D 前缀和来在 O(1) 中回答查询。 

这将问题从事件处理转变为静态网格预处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(NM + QN) | O(N) | 太慢了|
 | 网格+前缀和| O(N + M + 1000² + Q) | O(1000²) | 已接受 |

 ## 算法演练

 我们将所有信息压缩到固定的 1000×1000 网格中，以便每个单元的操作变得恒定时间。 

1. 构建二维数组`stars[x][y]`计算每个坐标处存在多少颗星星。 这是必要的，因为多个恒星可以占据相同的位置，并且我们必须保持多重性。 
2. 构建第二个二维数组`bad[x][y]`初始化为零。 这将标记所有受至少一个黑洞影响的细胞。 
3. 对于 (x, y) 处的每个黑洞，将正方形中从 (x−1, y−1) 到 (x+1, y+1) 的所有单元标记为坏单元，注意将边界限制在网格限制内。 这显式地扩展了黑洞效应，因此我们可以避免以后逐星检查。 我们立即扩展的原因是将几何条件转换为预先计算的布尔网格。 
4. 构建最终网格`valid[x][y]`使得它等于`stars[x][y]`如果电池没有坏，否则为零。 此步骤将破坏折叠成一个简单的过滤器。 
5. 构造一个 2D 前缀和`valid`。 每个前缀单元存储矩形中从 (0,0) 到 (x,y) 的有效星星的累积和。 这使得恒定时间矩形查询成为可能。 
6. 对于每个查询矩形 (x1, y1, x2, y2)，标准化坐标，使 x1 ≤ x2 且 y1 ≤ y2，然后在前缀网格上使用包含-排除计算总和。 

### 为什么它有效

 正确性来自于分离关注点。 黑洞效应仅取决于局部邻域，因此在考虑任何查询之前可以完全解决它们。 一旦我们将破坏转换为网格上的静态掩码，剩下的问题就纯粹是固定矩阵上的 2D 范围和查询。 前缀和不变量保证每个单元贡献在任何查询的矩形中都被精确计算一次，并且没有被破坏的单元贡献，因为它在前缀构造之前被显式归零。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAX = 1000

def main():
    N, M, Q = map(int, input().split())

    stars = [[0] * MAX for _ in range(MAX)]
    bad = [[0] * MAX for _ in range(MAX)]

    for _ in range(N):
        x, y = map(int, input().split())
        stars[x][y] += 1

    for _ in range(M):
        x, y = map(int, input().split())
        for dx in (-1, 0, 1):
            for dy in (-1, 0, 1):
                nx, ny = x + dx, y + dy
                if 0 <= nx < MAX and 0 <= ny < MAX:
                    bad[nx][ny] = 1

    valid = [[0] * MAX for _ in range(MAX)]
    for i in range(MAX):
        for j in range(MAX):
            if not bad[i][j]:
                valid[i][j] = stars[i][j]

    pref = [[0] * (MAX + 1) for _ in range(MAX + 1)]

    for i in range(1, MAX + 1):
        for j in range(1, MAX + 1):
            pref[i][j] = (
                valid[i - 1][j - 1]
                + pref[i - 1][j]
                + pref[i][j - 1]
                - pref[i - 1][j - 1]
            )

    def query(x1, y1, x2, y2):
        x1, x2 = min(x1, x2), max(x1, x2)
        y1, y2 = min(y1, y2), max(y1, y2)
        x1 += 1
        y1 += 1
        x2 += 1
        y2 += 1
        return (
            pref[x2][y2]
            - pref[x1 - 1][y2]
            - pref[x2][y1 - 1]
            + pref[x1 - 1][y1 - 1]
        )

    out = []
    for _ in range(Q):
        x1, y1, x2, y2 = map(int, input().split())
        out.append(str(query(x1, y1, x2, y2)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```该实现首先将星星压缩到频率网格中，以便自然地处理重复项。 黑洞步骤明确地绘制了 3×3 邻域，这避免了以后重复的几何检查。 前缀和数组是用一索引构建的，以简化边界处理，这就是为什么所有查询坐标都移动一的原因。 包含-排除公式是标准的 2D 范围和恒等式，也是查询变为 O(1) 的唯一原因。 

这里的一个常见错误是忘记坐标是包容性的并且很小。 另一个是未能限制黑洞的影响，这将导致索引错误。 一个更微妙的问题是忘记积累星星而不是覆盖它们。

 ## 边缘情况

 一个关键的边缘情况是重叠黑洞。 如果一个位于 (5,5)，另一个位于 (6,6)，则算法标记两个 3×3 邻域中的所有单元。 第二个标记不会撤消或重复计算任何内容，因为`bad[x][y]`是布尔值。 这确保了最终掩模是稳定的，无论重叠顺序如何。 

另一个边缘情况是恒星恰好位于黑洞 3×3 区域的边界上。 对于 (2,2) 处的黑洞，(1,3) 处的一颗恒星仍会被移除，因为它位于两个轴的一个单位内。 dx 和 dy 上的显式循环保证包含所有边界单元。 

最后，覆盖整个网格的查询测试前缀和是否正确累积所有有效星星。 即使许多恒星共享坐标，包含-排除结构也能确保不会出现过度计数。
