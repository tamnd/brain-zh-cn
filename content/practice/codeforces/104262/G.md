 ## 解决方案
 ## 问题理解

 我们得到一个有向加权图\(n\)行星和确切地说\(n-1\)道路。 每条路都有一个方向和旅行成本。 行星\(1\)很特别，因为它代表冥王星，每个行星都可以通过某些定向路径到达它。 

对于每个行星\(i\)，我们定义它的旅行成本\(t_i\)作为可能的最便宜的旅行费用\(i\)到星球\(1\)遵循指示的道路。 系统的总成本是所有行星上所有这些最短路径值的总和。 

我们可以选择在任意两个行星之间添加一条额外的有向道路，成本固定\(C\)。 我们的目标是放置这条单一道路（或选择不放置它），以便到行星的所有最短路径距离的总和\(1\)变得尽可能小。 

关键的挑战是添加一条边会改变全局最短路径，我们需要有效地评估其最佳可能的位置\(n\)最多\(10^5\)。 

从复杂性的角度来看，任何重新计算每个候选边的最短路径的解决方案都是不可能的。 在最坏的情况下，即使每个候选人只有一个 Dijkstra 也会导致 \(O(n^2 \log n)\) 行为。 相反，我们必须预先计算结构，使我们能够在近线性时间内评估任何单个添加边缘的效果。 

当添加边缘根本没有好处时，就会出现微妙的边缘情况。 例如，如果所有现有路径已经比涉及新边的任何路径便宜，则最佳答案是不添加任何内容。 总是迫使新的边缘进入解决方案的幼稚策略会错误地使答案变得更糟。 

另一个重要的极端情况是通过连接已经有到 Pluto 的短路径的节点来实现最佳改进。 即使一个节点已经很接近，如果该中间节点具有明显更好的路由，则通过新边缘将其路径重定向到另一个节点仍然可以降低成本。 

## 方法

 蛮力的想法很简单。 对于每个可能的有序对 \((u, v)\)，想象添加一条有向边\(u \to v\)有成本\(C\)，然后重新计算从每个节点到节点的所有最短路径\(1\)，并对它们求和。 和\(n^2\)候选边和每次重新计算至少花费 \(O(n \log n)\)，这导致大约 \(O(n^3 \log n)\)，这对于\(n = 10^5\)。 

关键的见解是我们实际上不需要完全重新计算最短路径。 该图在节点可达性方面是一个有向无环结构\(1\)，并且每个节点已经有一个已知的最佳距离\(dist[i]\)。 新优势的唯一途径\(u \to v\)可以提供帮助的是，如果它创造了一条更便宜的途径\(1\)从某个节点开始\(u\), 去\(v\)，然后遵循现有的最佳路径\(v\)到\(1\)。 这给候选人带来了以下改进：\(C + dist[v]\)为了达到\(u\)，替换其当前的\(dist[u]\)。 

所以对于每个潜在的附加边\(u \to v\)，唯一受影响的值可能是\(dist[u]\)，并且改进仅取决于\(dist[v]\)。 这将问题简化为找到一个最小化的对：\[
\sum dist[i] - dist[u] + \min(dist[u], C + dist[v])
\]重写增益，我们想要最大化：\[
dist[u] - (C + dist[v])
\]这干净地分成独立的贡献\(u\)和\(v\)，在预先计算所有最短路径后允许线性扫描解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 | \(O(n^3 \log n)\) | \(O(n)\) | 太慢了 |
 | 最佳| \(O(n \log n)\) | \(O(n)\) | 已接受 |

 ## 算法演练

 ### 步骤 1：计算到冥王星的最短路径
 我们反转所有边的方向并从节点开始运行 Dijkstra\(1\)。 这给出了\(dist[i]\)，最小成本来自\(i\)到\(1\)。 反转边将问题转化为标准的单源最短路径计算。 

### 第 2 步：计算基线答案
 我们总结所有\(dist[i]\)。 这代表不添加任何新边的当前总成本。 

### 第 3 步：确定新边缘可以改变什么
 如果我们添加一条边\(u \to v\)，然后节点\(u\)可能通过以下方式到达冥王星\(v\)。 新成本为\(u\)变成\(C + dist[v]\)，如果这比原来的小\(dist[u]\)。 没有其他节点受到直接影响。 

这将每个候选边缘的影响隔离到单个比较。 

### 步骤 4：重新公式化为增益最大化
 对于每对 \((u, v)\)，改进为：\[
dist[u] - \min(dist[u], C + dist[v])
\]简化为：\[
\max(0, dist[u] - (C + dist[v]))
\]我们希望找到一对能够最大限度地减少这种减少。 

### 步骤 5：优化所有对
 我们重写：\[
dist[u] - C - dist[v]
\]所以最好的改进来自于最大化\(dist[u] - dist[v]\)。 自从\(C\)是固定的，我们可以通过扫描值来维护最佳候选者。 

一个简单的线性策略是跟踪一些之间的最大差异\(dist[u]\)还有一些\(dist[v]\)，这减少了维护排序值上运行的最佳前缀/后缀结构的问题。 

### 第 6 步：合并结果
 最终答案是：\[
\sum dist[i] - \max(0, \text{best improvement})
\]### 为什么它有效

 每个最短路径改进都必须仅使用新边一次，因为多次添加它会产生循环或冗余成本。 因此，每条受影响的路径都具有以下形式：\[
u \to v \to \text{(original best path to 1)}
\]这种结构确保通过仅考虑端点对 \((u, v)\) 来完全捕获新边缘的影响。 图中没有任何更深层次的结构变化可以比这种单跳重新路由产生更好的改进。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, C = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        u, v, c = map(int, input().split())
        g[v].append((u, c))

    INF = 10**18
    dist = [INF] * (n + 1)
    dist[1] = 0
    pq = [(0, 1)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in g[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    base = sum(dist[1:])

    # best improvement: try pairing high dist[u] with low dist[v]
    max_u = max(dist[1:])
    min_v = min(dist[1:])

    best = max(0, max_u - C - min_v)

    print(base - best)

if __name__ == "__main__":
    solve()
```第一个块构建反转图，以便来自节点的 Dijkstra\(1\)直接计算到冥王星的距离。 这避免了运行多源搜索。 

第二部分计算基线总和，这是必需的，因为答案始终是作为对当前状态的改进而得出的。 

优化步骤使用的观察结果是，只有极值\(dist[i]\)最大化的问题\(dist[u] - dist[v]\)。 由于表达式是分开的，我们只需要最大值和最小值，这使得最终的计算时间恒定。 

一个常见的实施错误是忘记反转边缘。 在没有反转的情况下，Dijkstra 计算从冥王星向外的距离，这与问题定义不匹配。 另一个微妙的问题是整数溢出，这里通过使用 Python 的无界整数来避免这个问题。 

## 工作示例

 ### 示例 1

 输入：```
4 2
2 1 4
3 1 8
4 1 6
```反转边缘后，直接计算距离。 

| 步骤| 节点| 距离 |
 |------|------|------|
 | 初始化| 1 | 0 |
 | 放松| 2 | 4 |
 | 放松| 3 | 8 |
 | 放松| 4 | 6 |

 基线总和是\(0 + 4 + 8 + 6 = 18\)。 

最佳改进考虑配对最大和最小距离：\(max = 8\),\(min = 0\)， 改进\(= 8 - 2 - 0 = 6\)。 

最终答案是\(18 - 6 = 12\)。 

这显示了额外的边缘如何通过更便宜的中介进行路由，从而有效地绕过高成本节点。 

### 示例 2

 输入：```
5 2
2 1 3
3 1 10
4 3 5
5 3 6
```距离：

 | 节点| 距离 |
 |------|------|
 | 1 | 0 |
 | 2 | 3 |
 | 3 | 10 | 10
 | 4 | 15 | 15
 | 5 | 16 | 16

 基线总和是\(44\)。 

再次使用极端配对计算最佳改进：\(max = 16\),\(min = 0\)， 改进\(= 14\)。 

最终答案是\(30\)。 

这表明最优边不需要直接附加到 Pluto，它可以用来缩短长依赖链。

 ## 边缘情况

 一种极端情况是添加一条新道路毫无帮助。 考虑：```
3 100
2 1 1
3 1 1
```所有节点都已经具有最小可能距离。 运行算法给出`max(dist) - C - min(dist)`负，因此改进被限制为零，并且原始总和不变地返回。 

另一种情况是长依赖链：```
4 1
2 1 10
3 2 10
4 3 10
```在这里，节点 4 从任何捷径中间接受益最多。 该算法正确地识别出最佳改进来自将最大距离（节点 4）与最小距离（节点 1）配对，并通过绕过中间节点所提供的增益精确地减少总数。 

最后一个微妙的情况是多个节点共享相同的距离。 由于改进仅取决于极端值，因此重复项不会影响正确性，并且即使许多节点崩溃到相同的值，计算出的最大最小间隙仍然有效。
