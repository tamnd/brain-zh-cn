 ## 解决方案
 ## 问题理解

 我们得到了一个完整的加权图$N$顶点，其中每个顶点代表一块岩石。 成本$C_{i,j}$是直接粘岩石的价格$i$岩石旁边$j$。 目标是将所有岩石按循环顺序排列，以便每个岩石恰好有两个邻居，并且我们支付循环中每个邻接的成本。 总成本是该周期中所有连续对的成本之和，包括从最后一块岩石回到第一块岩石的封闭环的边缘。 

所以任务是选择所有的排列$N$岩石，将其解释为一个循环，并最小化该循环中相邻边缘成本的总和。 

约束很小，$N \le 12$，这立即表明指数状态探索是可能的。 所有排列的阶乘解，大致如下$12! \approx 4.8 \times 10^8$, 已经是边界，但如果天真地完成，在 Python 中仍然太大。 任何解决方案都必须压缩对称性或对子集使用动态规划。 

一个关键的结构观察是循环具有旋转对称性。 相同排列的任何循环旋转都会产生相同的成本，因此强力排列计数浪费了一个因子$N$。 更重要的是，我们不仅需要排列，还需要确保闭环，这会在第一个元素和最后一个元素之间引入依赖关系，从而破坏更简单的贪婪或增量构造。 

当所有成本相同或为零时，就会出现微妙的边缘情况。 在这种情况下，任何循环都是最佳的，但是忘记添加结束边或重复计数边的简单算法仍然会产生不正确的结果。 例如，如果$N=4$并且所有成本都是零，正确答案是零。 仅对连续对求和而不关闭循环的错误解决方案也会在此处输出零，从而隐藏错误，因此必须在结构上强制执行正确性，而不是凭经验检查。 

当最佳循环不唯一时，会出现另一种边缘情况。 例如，不对称的局部选择仍然可以产生全局最优循环。 任何尽早修复最近邻居的贪婪方法都会失败，因为局部最小边缘不能保证全局一致的循环。 

## 方法

 最直接的想法是枚举岩石的每一种可能的排序并计算相应循环的成本。 对于每个排列，我们求和$C_{p_i, p_{i+1}}$加上环绕边缘$C_{p_{N}, p_1}$。 这是正确的，因为它明确地评估每个有效周期。 然而，它需要$N!$排列和$O(N)$每个排列的工作，导致$O(N \cdot N!)$，这对于$N=12$远远超出了可行的限度。 

这种方法的冗余来自于以下事实：相同的偏序出现在许多排列中。 一旦选定顶点的前缀被固定，剩余的结构仅取决于哪些顶点仍然未使用以及哪个顶点当前位于路径的末尾。 这提出了一种状态压缩的想法：我们不跟踪完整的排列，而是跟踪子集。 

这自然会导致位掩码动态编程公式。 我们定义一个状态，表示我们已经选择了顶点的子集并且当前结束于特定顶点。 存储在状态中的成本是形成以某种顺序精确访问这些顶点并在该顶点结束的路径的最小成本。 过渡通过添加一个未使用的顶点来扩展路径。 

最终答案是通过关闭循环获得的：一旦使用了所有顶点，我们从最后一个端点返回到起始顶点并添加最后一条边。 

这将问题从阶乘排列简化为$O(N^2 2^N)$状态，这对于$N \le 12$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 |$O(N \cdot N!)$|$O(N)$| 太慢了|
 | 路径上的位掩码 DP |$O(N^2 2^N)$|$O(N 2^N)$| 已接受 |

 ## 算法演练

 我们固定一个顶点作为起点来消除旋转对称性。 不失一般性，我们选择顶点 0 作为循环的起点。 每个有效周期都可以旋转，使其从 0 开始。 

我们定义一个 DP 表，其中`dp[mask][i]`表示从0开始，精确访问中的顶点的最小成本`mask`，并在顶点结束`i`。 

1. 将DP表初始化为无穷大。 放`dp[1 << 0][0] = 0`因为我们从顶点 0 开始，没有任何成本。 
2. 迭代包含顶点 0 的所有掩码。对于每个掩码和每个端点`i`在面具内，尝试过渡。 
3. 对于每个当前状态`(mask, i)`，尝试通过添加顶点来扩展路径`j`不在`mask`。 新的状态变成`(mask | (1 << j), j)`，成本增加`C[i][j]`。 我们更新`dp`具有尽可能小的值。 
4.处理完所有状态后，我们只考虑其中的状态`mask`包括所有顶点。 对于每个可能的结束顶点`i`，我们通过增加成本来结束循环`C[i][0]`。 
5. 答案是所有此类全掩码端点的最小值。 

固定起始顶点有效的原因是任何循环都可以旋转到从 0 开始而不改变其成本。 这消除了不同旋转中相同循环的冗余计数，从而将状态空间减少了$N$。 

## 为什么它有效

 在每个 DP 状态，我们都保持以下不变式：`dp[mask][i]`是恰好访问以下顶点的所有路径中的最小成本`mask`并结束于`i`。 每个转换都通过添加一个未使用的顶点来保持有效性，因此不会发生无效的重新访问。 

由于从顶点 0 开始的每个排列恰好对应于一个 DP 转换序列，因此表示从 0 开始的所有可能的哈密顿路径。 在最后正确地关闭循环可以解决丢失的最终边缘的问题，并且由于每个循环都有一个从 0 开始的代表，因此可以保证考虑最佳循环。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = [list(map(int, input().split())) for _ in range(n)]
    
    INF = 10**18
    dp = [[INF] * n for _ in range(1 << n)]
    
    dp[1][0] = 0
    
    for mask in range(1 << n):
        if not (mask & 1):
            continue
        for i in range(n):
            if not (mask & (1 << i)):
                continue
            cur = dp[mask][i]
            if cur == INF:
                continue
            for j in range(n):
                if mask & (1 << j):
                    continue
                nmask = mask | (1 << j)
                val = cur + c[i][j]
                if val < dp[nmask][j]:
                    dp[nmask][j] = val
    
    full = (1 << n) - 1
    ans = INF
    for i in range(n):
        ans = min(ans, dp[full][i] + c[i][0])
    
    print(ans)

if __name__ == "__main__":
    solve()
```DP 表使用较大的哨兵值进行初始化，以便无法到达的状态不会干扰最小转换。 起始状态使用mask`1`因为只包含顶点 0。 

掩码、当前端点和下一个顶点的三重循环是核心转换引擎。 它系统地尝试部分路径的每一种可能的扩展而不重复。 

最后的循环通过返回起始顶点来显式地关闭循环，确保完全考虑到圆形结构。 

这里的一个常见错误是忘记强制路径始终从 0 开始。 如果没有这个，同一周期的旋转将被多次计算，但最小值将保持正确，尽管存在冗余计算。

 ## 边缘情况

 一个重要的边缘情况是当$N=2$。 DP 仍然有效，但只有一个可能的循环：0 → 1 → 0。状态转换永远不会分支，最终答案很简单$C_{0,1} + C_{1,0}$。 该算法自然地处理这个问题，因为 DP 表仅包含两个相关状态，并且关闭步骤显式添加返回边沿。 

另一种情况是所有成本为零。 每个哈密顿循环的成本为零，并且动态规划将在所有状态中传播零。 无论路径选择如何，最终的最小值都保持为零，这证实了该算法不依赖于平局决胜。 

第三种情况是当一条边与其他边相比非常大时。 DP 正确地避免了它，因为它总是考虑所有可能的转换并保留完整路径中的最小值。 即使局部廉价的边缘导致全局昂贵的完成，状态空间探索也确保评估和选择更便宜的替代路线。
