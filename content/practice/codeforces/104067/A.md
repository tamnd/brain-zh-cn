 ## 解决方案
 ## 问题理解

 我们在一个小整数范围内得到多个独立的查询。 每个查询提供一个区间$[l, r]$和一个数字$k$。 对于每个整数$x$，我们将其分解为素数，并计算该分解中出现的素因数，并计算重数。 所以$12 = 2^2 \cdot 3$贡献$3$因素，同时$18 = 2 \cdot 3^2$也做出了贡献$3$。 

一个号码被称为$k$-“可怕”，如果质因数的数量恰好是$k$。 对于每个查询，我们必须计算给定段中有多少个整数恰好具有$k$主要因素。 

输入约束已经强烈地塑造了解决方案。 的价值观$l$和$r$至多是$10^5$，因此数字的范围足够小，我们可以为每个整数预处理一次属性。 但查询数量很大，最多$10^5$，因此每个查询重新计算因式分解会太慢。 将每个查询中的每个数字进行因子分解的简单方法会导致粗略的结果$10^5 \times 10^5$的操作，远远超出了可接受的范围。 

参数$k$也很小，以 16 为界，这表明素因子计数的分布很浅并且可以有效地预先计算。 

微妙的边缘情况来自像 1 这样的小数字。数字 1 的质因数为零。 如果查询要求$k = 0$，它应该被计算，但许多幼稚的实现完全忽略 1，因为它没有素数分解。 另一个问题是正确计算重数。 例如，8 应该贡献 3，而不是 1，因为$8 = 2^3$。 这里的错误会导致系统性的低估。 

## 方法

 暴力解决方案通过将每个数字分解来直接处理每个查询$[l, r]$使用试除法。 这在概念上很简单：对于每个数字，重复除以素数并计算因子。 这是正确的，但其成本是由重复因式分解驱动的。 即使用筛子，这样做$10^5$超过尺寸范围的次数$10^5$结果约为$10^{10}$最坏情况下的操作，是无法通过的。 

关键的观察是所有数字都在固定的小范围内，因此它们的素因子计数可以预先计算一次。 我们不是重新计算每个查询的因式分解，而是计算一个函数$f[x]$等于质因数的个数$x$。 一旦知道这个数组，每个查询就变成静态数组上的范围计数问题。 

使用前缀和可以有效地处理许多查询的范围计数。 对于每个可能的值$k$，我们构建一个前缀数组$pref[k][x]$最多存储多少个数字$x$正好有$k$主要因素。 然后，每个查询都会减少为常数时间减法。 

这将问题从重复的数论计算转变为预处理步骤加上快速查找。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(q \cdot (r-l+1)\sqrt{n})$|$O(1)$| 太慢了|
 | 最优（筛+前缀和）|$O(N \log \log N + q)$|$O(NK)$| 已接受 |

 ## 算法演练

 我们预处理所有数字$N = 10^5$。 

1. 构建数组`spf`或者使用类似筛子的方法直接计算最小素数，以便可以快速分解每个数字。 这避免了从头开始重新计算每个数字的整除性检查。 
2. 对于每个整数$x$从 2 到$N$，计算其具有重数的质因数总数。 我们反复划分$x$乘其最小质因数并累加计数。 这会产生一个值`cnt[x]`。 
3.自从$k$最多 16，我们为每个可能的构建前缀和$k$。 我们维持`pref[k][i]`，其中存储了多少个数字$[1, i]$正好有$k$主要因素。 我们通过传播以前的值并在以下情况下加 1 来增量填充它：`cnt[i] == k`。 
4. 对于每个查询$(l, r, k)$，我们在常数时间内回答：$$pref[k][r] - pref[k][l-1]$$5. 输出每个查询的结果。 

主要的实现问题是保持因式分解线性或接近线性。 使用最小素因子预处理可确保每个数字在实践中以对数时间分解。 

### 为什么它有效

 正确性依赖于两个不变量。 第一的，`cnt[x]`正是质因数的总数$x$，因为除法的每一步恰好删除了一个素因数，并且所有因数都是通过重复除以最小素数来计算的。 其次，前缀数组维护每个前缀出现的累积计数$k$-班级。 由于每个整数都独立地贡献于一个$k$，前缀差异精确地隔离任何段上的计数，没有重叠或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

N = 100000

spf = list(range(N + 1))

for i in range(2, int(N ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, N + 1, i):
            if spf[j] == j:
                spf[j] = i

cnt = [0] * (N + 1)

for i in range(2, N + 1):
    x = i
    c = 0
    while x > 1:
        p = spf[x]
        while x % p == 0:
            x //= p
            c += 1
    cnt[i] = c

MAXK = 16
pref = [[0] * (N + 1) for _ in range(MAXK + 1)]

for i in range(1, N + 1):
    for k in range(MAXK + 1):
        pref[k][i] = pref[k][i - 1]
    k = cnt[i]
    if k <= MAXK:
        pref[k][i] += 1

q = int(input())
out = []

for _ in range(q):
    l, r, k = map(int, input().split())
    if k > MAXK:
        out.append("0")
    else:
        out.append(str(pref[k][r] - pref[k][l - 1]))

print("\n".join(out))
```该解决方案首先构建最小的质因数，以便因式分解变得确定性且快速。 然后，每个数字都被缩减为其素数分量，正确地累加重数，而不仅仅是不同的素数。 前缀表的构建方式是每行对应一个固定的$k$，因此查询不需要扫描范围。 

一个常见的实施陷阱是忘记 1 贡献 0 个因子。 在这里它自然被处理，因为`cnt[1]`保持为零并包含在前缀中$k = 0$。 

另一个微妙的问题是有效更新前缀数组。 重新计算每个的完整计数$k$每个索引独立会太慢； 相反，我们复制以前的前缀值并仅更新相关的$k$每个索引的存储桶。

 ## 边缘情况

 对于值 1，算法分配`cnt[1] = 0`通过初始化隐式地进行。 当查询要求$k = 0$，前缀数组正确地包含 1，因为它只向零类存储桶贡献一次。 

对于大型$k$例如 15 或 16 等值，该范围内的许多数字都未达到该因子计数。 前缀表仍然可以安全地处理它们，因为这些存储桶在整个预处理过程中保持为零，因此减法会产生零，而无需特殊情况逻辑。 

查询$l = 1$依赖于访问`pref[k][0]`。 前缀数组在索引 0 处用零初始化，因此减法`pref[k][r] - pref[k][0]`正确返回全范围计数，没有下溢或索引错误。
