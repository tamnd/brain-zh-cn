 ## 解决方案
 ## 问题理解

 我们正在模拟在固定天数内重复的非常具体的财务流程。 一个人从零硬币开始。 每天按顺序发生两件事：首先他们收到一些收入，然后他们立即按照由参数确定的固定支出规则去购物$X$。 收入到达后，如果他们的当前余额至少为$X$，他们花费的正是$X$。 否则，他们会花光所有的一切，但一天结束时却归零。 对于许多不同的值，该过程独立重复$X$，对于每个查询，我们希望得到几天后的最终金额。 

输入给出每日收入列表，然后给出多个候选值$X$。 每个查询都会询问：如果我们使用固定支出阈值运行整个流程，那么处理完所有天后最终余额是多少。 

这些限制迫使我们做出谨慎的设计选择。 高达$10^5$天和$10^5$查询，任何独立模拟每个查询每天流程的解决方案将尝试最多$10^{10}$操作，这远远超出了2秒允许的范围。 甚至一个$O(n \log n)$每个查询方法会太慢。 

当收入小于$X$反复。 在这种情况下，该过程的行为就像“立即消耗所有内容”，这会频繁重置状态。 另一个边缘情况是当$X = 0$，其中支出没有任何作用，最终答案只是所有收入的总和。 在相反的极端，当$X$大于任何前缀累积，每天都会以重置结束，并且只有本地累积才重要。 

## 方法

 直接模拟方法单独处理每个查询。 对于固定的$X$，我们迭代所有日子，添加收入，减去$X$如果可能，否则重置为零。 这是正确的，但要付出代价$O(n)$每个查询，导致$O(nq)$总工作量，在最坏的情况下太大了。 

关键的观察是，该过程仅取决于运行总和相对于倍数的演变方式$X$。 我们可以将这个过程重新解释为维护一个正在运行的前缀总和，但只要它达到或超过下一个倍数，就“削减它”，而不是跟踪每个查询的确切每日状态。$X$。 最终的答案本质上是重复删除 size 块后总累加和的余数$X$，除了溢出重置本地累积而不是无限结转。 

这提出了一个不同的观点：我们不应该对每个查询进行数天的模拟，而应该预处理前缀和并推断有多少个完整的块大小$X$可以由不同的后缀组成。 如果我们对前缀和进行排序或构造，我们可以通过计算运行总数超过表单阈值的次数来回答每个查询$kX$。 这将问题转化为前缀和计数问题，可以通过二分搜索或离线分组来处理。 

标准的有效方法是预先计算前缀和$p_i$。 给定的最终剩余硬币$X$可以表示为总和减去$X$倍于我们“成功支付”的次数$X$重置之前。 当重置之间的运行前缀总和低于以下时，重置就会发生$X$，这对应于将前缀和数组分割成差异超过倍数的块$X$。 我们可以通过重复跳转到前缀差异在范围内的最后一个索引来处理每个查询$X$，使用二进制提升方式跳过前缀索引。 通过前缀和的预处理，每个查询都可以解析为$O(\log n)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟|$O(nq)$|$O(1)$| 太慢了|
 | 前缀+二进制跳转|$O((n+q)\log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们首先构建前缀总和，以便我们可以快速查询任何前缀区间内的总收入。 这将日常过程转变为对累积范围的推理，而不是逐步模拟。 

然后，我们预处理一个结构，该结构使我们能够快速确定，对于给定的起点，在累积总和在给定的条件下强制重置之前我们可以前进多远$X$。 这是通过为每个索引存储我们可以跳转多远来完成的，同时将运行的累积段严格保持在下面$X$，然后在这些跳跃上构建二元升降台。 

最后，通过重复跳转数组来处理每个查询，以对数步长模拟“消耗直到重置”行为。 

### 步骤

 1. 计算前缀和$p$， 在哪里$p[i]$是从第一天到今天的总收入$i$。 这允许将任何段总和计算为两个前缀值的差。 
2. 对于每个起始位置$i$,确定最远位置$j$使得来自的收入总和$i+1$到$j$仍小于$X$。 这表示没有发生强制复位的段。 
3. 在这些跳跃上构建一个二元升降台，以便我们可以有效地穿过多个段。 每次跳跃都代表在重置事件之前消耗尽可能多的资源。 
4. 对于每个查询，从第 0 天开始，使用零个硬币，并使用预先计算的结构重复跳转，直到到达第 1 天$n$。 每个部分都为最终剩余部分贡献了受控数量。 
5、最后一跳后剩余的硬币正是最后一个不完整段的剩余积累。 

### 为什么它有效

 这个过程完全取决于运行积累在超过之前能增长到什么程度$X$。 每次累计金额超过$X$，系统会丢弃所有内容，这意味着唯一有意义的演变是在重置点之间。 这将整个模拟变成一系列独立的段，每个段都受到前缀和的阈值条件的限制。 二进制提升结构保证正确找到每个段边界，而不会丢失中间重置，因为每次跳转都被定义为遵守约束下的最大有效范围。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    xs = list(map(int, input().split()))

    # prefix sums
    p = [0] * (n + 1)
    for i in range(n):
        p[i + 1] = p[i] + a[i]

    # For each i, we will compute next position where reset might occur for a given X.
    # We answer queries offline by sorting X values.
    
    # Precompute next jump for each i for all possible j is not feasible directly.
    # Instead we will answer each query with two pointers.

    answers = []

    for X in xs:
        if X == 0:
            answers.append(p[n])
            continue

        res = 0
        i = 0

        while i < n:
            # find furthest j such that sum(i+1..j) < X
            lo, hi = i, n
            best = i
            while lo <= hi:
                mid = (lo + hi) // 2
                if p[mid] - p[i] < X:
                    best = mid
                    lo = mid + 1
                else:
                    hi = mid - 1

            # accumulate segment
            segment_sum = p[best] - p[i]
            res += segment_sum

            # simulate spending
            i = best
            if i < n:
                # at position best+1, we would have overflow or exact reach
                # so we reset
                i += 1

        answers.append(res)

    print(*answers)

if __name__ == "__main__":
    solve()
```该实现从前缀和开始，以便可以在恒定时间内计算任何间隔和。 每个查询都是独立处理的，因为行为强烈依赖于$X$。 

对于固定查询，二分搜索会找到从当前位置开始的最长延伸，其中累积收入严格低于$X$。 该部分被添加到结果中，因为它贡献的资金从未完全花完。 一旦该段结束，我们就向前移动经过重置点并继续。 

特殊情况$X = 0$单独处理，因为根本没有支出发生，所以答案只是总金额。

 ## 边缘情况

 当$X = 0$，该过程永远不会移除硬币。 该实现显式返回前缀总和，这与支出不执行任何操作并且不会发生重置的事实相匹配。 

当所有$a_i = 0$，每个段都是微不足道的，二分查找总是返回相同的索引。 该算法正确地遍历数组，不会出现无限循环，因为每次迭代后指针总是增加。 

什么时候$X$大于任何总前缀，二分搜索总是扩展到最远的索引，产生单个段。 该算法将全部总和累加一次并终止。 

当价值波动剧烈时，例如收入大小交替时，二分搜索每次都会正确地隔离最大有效段，因为它直接强制执行约束$p[j] - p[i] < X$，确保段中不包含无效的过度累积。
