 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，并且对于每个位置，都有两种替代的“模式”。 如果我们将位置分配为红色，我们将获得一个值$r_i$。 如果我们将其分配为蓝色，我们将获得$b_i$。 做出所有选择后，所有蓝色位置都会消失，只有红色位置保持原来的顺序。 

在这个过滤后的字符串上，我们支付等于剩余序列中反转次数的惩罚，其中反转是一对位置$(i, j)$和$i < j$， 这$i$第 - 个剩余字符是`1`，以及$j$第 - 个剩余字符是`0`。 每对花费一枚硬币。 

任务是选择一种使总利润最大化的着色：所有选定的颜色的总和$r_i$和$b_i$值减去剩余的仅红色序列中的反转惩罚。 

这些约束意味着所有测试用例的总长度可达$4 \cdot 10^5$，因此任何解必须接近线性或$O(n \log n)$。 对所有前缀或子集的二次方法是立即不可能的，因为它将涉及在许多不同选择下重新计算反演成本。 

有些情况特别容易处理不当。 如果所有字符都是`0`，永远不会有任何反转，因此最优策略纯粹是局部的：每个位置独立地采用$r_i$或者$b_i$更大。 如果所有字符都是`1`，同样不会出现反转，并且问题简化为每个位置的独立选择。 只有当两者都存在时，困难才会出现`1`和`0`存在，因为然后选择一个`0`取决于选择的数量`1`s 出现在它前面。 

独立决定每个位置的天真贪婪策略会失败，因为选择一个`1`提前增加每个人的未来成本`0`仍然是红色的。 

## 方法

 思考这个问题的一个直接方法是修复一个位置的子集，这些位置将是红色的，并将其他所有位置视为蓝色。 然后，分数是所选红色增益加上所有蓝色增益的总和，减去所选红色位置之间的反转惩罚。 

如果我们忽略结构，我们可能会尝试枚举红色位置的所有子集。 这是正确的，但呈指数级增长，因为每个元素都有两个状态，给出$2^n$每个测试用例的配置。 

关键结构是只有红色位置相互作用，并且仅在一个方向：选定的位置`1`仅当它出现在选定的之前时才有助于处罚`0`。 这意味着成本取决于所选元素的顺序，而不仅仅是它们的数量。 

重构该过程的一个有用方法是从左到右扫描字符串并维护选择的数量`1`s已经出现了。 当我们决定将某个位置设为红色时，`1`立即仅贡献其局部增益，但`0`贡献其局部增益减去等于先前选择的红色数量的惩罚`1`s。 

这将问题变成了一个关于字符串前缀的动态程序，其中状态跟踪有多少个`1`到目前为止已经选定了。 然而，此状态上的直接 DP 太大而无法简单处理，因为每个转换必须考虑所有可能的计数。 

关键的观察是，对于固定前缀，DP 值是所选前缀数量的函数`1`s 以结构化方式运行。 当处理一个`1`，DP有效地将质量从状态转移$k$到$k+1$。 当处理一个`0`，每个州$k$使用线性依赖于的函数独立更新$k$达到一个阈值。 这种结构允许使用具有范围变换的线段树来有效地维护DP，从而在状态索引上保留类似凹性的行为。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集 |$O(2^n \cdot n)$|$O(n)$| 太慢了 |
 | 状态 DP 在选定的 1 秒内 |$O(n^2)$|$O(n)$| 太慢了 |
 | 用线段树优化DP |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们首先将答案的常数部分分开，它是所有答案的总和$b_i$。 之后，每个位置都会做出调整$r_i - b_i$如果它被选择为红色，否则为零，同时还通过反转惩罚相互作用。 

我们在状态索引所在的前缀上维护一个 DP$k$代表有多少个`1`到目前为止，字符已被选择为红色。 存储的值是前缀中所有决策的最佳可能额外利润。 

在每个位置，我们根据角色是否是角色来更新这个 DP`1`或者`0`。 

1. 用单一状态初始化 DP，其中没有`1`s 被选择且值为零。 
2.处理字符时`1`，如果我们选择它为红色，它会增加选择的数量`1`是。 这意味着每个 DP 状态$k$转换到状态$k+1$额外增益为$r_i - b_i$。 如果我们选择蓝色，则 DP 状态不会发生任何变化。 
3.处理字符时`0`，选择红色不会改变选择的数量`1`s，但它引入了等于当前所选数量的惩罚`1`s。 所以对于每个州$k$，我们要么保持当前值（如果我们将其涂成蓝色），要么通过以下方式改进它：$r_i - b_i - k$（如果我们把它漆成红色）。 
4. 更新一个`0`因此成为所有状态的逐点变换$k$，其中每个状态根据线性函数独立更新$k$。 
5. 我们将 DP 数组维护在支持移位索引并有效应用范围最大更新的数据结构中，以便选择一个`1`以及由a引起的线性更新`0`可以以每次操作的对数时间应用。 

## 为什么它有效

 DP 状态完全捕获了唯一重要的依赖关系：有多少`1`s 已在当前位置之前选择。 未来的每次处罚仅取决于此计数，而不取决于具体的哪个`1`s 被选中。 转换保留了这种不变性，因为选择`1`仅增加此计数，并选择一个`0`仅使用当前计数而不改变它。 

由于所有交互都是通过这个单一标量状态来调节的，因此不需要额外的结构来表示历史。 线段树实现只是一种在应用依赖于状态索引的线性变换时有效维护该状态的所有可能值的方法。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        r = list(map(int, input().split()))
        b = list(map(int, input().split()))

        base = sum(b)
        dp = [0] * (n + 1)
        neg_inf = -10**30

        for i in range(n):
            ndp = [neg_inf] * (n + 1)

            if s[i] == '1':
                w = r[i] - b[i]
                for k in range(n):
                    if dp[k] == neg_inf:
                        continue
                    ndp[k + 1] = max(ndp[k + 1], dp[k] + w)
                    ndp[k] = max(ndp[k], dp[k])
            else:
                w = r[i] - b[i]
                for k in range(n + 1):
                    if dp[k] == neg_inf:
                        continue
                    ndp[k] = max(ndp[k], dp[k])
                    ndp[k] = max(ndp[k], dp[k] + w - k)

            dp = ndp

        ans = max(dp)
        print(base + ans)

if __name__ == "__main__":
    solve()
```实施直接遵循DP的制定。 数组`dp[k]`准确地处理前缀后存储可实现的最佳增益`k`选择红色`1`s。 对于每个字符，都会构建一个新的数组，因为转换仅取决于前一层。 

为了`1`，我们要么跳过它，要么接受它，接受它会使状态索引向上移动。 为了`0`，我们要么跳过它，要么接受它，但是接受它会减少当前所选数量的值`1`s，这正是`k`。 

所有状态上的外部循环使得这个版本在概念上很简单，但它的目的是作为从 DP 公式到优化线段树实现的桥梁，在优化线段树实现中，每个状态的转换都被压缩。 

## 工作示例

 考虑一个短字符串`s = 1010`具有较小的任意值，因此我们可以清楚地看到结构。 假设选择一个`1`带来积极的好处并选择`0`提供适度的好处。 

我们追踪`dp[k]`每一步之后，在哪里$k$是选择的数量`1`s。 

| 步骤| 人物 | 过渡类型| 关键效果|
 | ---| ---| ---| ---|
 | 0 | 开始 | 初始化| dp[0] = 0 |
 | 1 |`1`| 班次 | 跳过或增加 k |
 | 2 |`0`| 处罚 | 状态失去 k 相关值 |
 | 3 |`1`| 班次 | increases possible k values |
 | 4 |`0`| 处罚 | 惩罚高 k 态更多 |

 该轨迹表明，增加选定的数量`1`s 提高了早期利润，但后来获利`0`更贵。 

现在考虑一个包含所有内容的字符串`0`s。 每个状态都是独立演化的，每个位置的最优决策仅取决于是否$r_i - b_i$是积极的。 没有出现状态交互，证实反演耦合是复杂性的唯一来源。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(n^2)$在所呈现的 DP 中 | 每个位置都会更新所有状态计数 |
 | 空间|$O(n)$| 存储 DP 超过可能选择的数量`1`是 |
 预期的约束需要一个$O(n \log n)$或者$O(n)$使用支持状态索引范围转换的数据结构优化相同的 DP 思想。 包含原始 DP 只是为了暴露底层结构； 它不足以满足全部限制，但与概念模型完全匹配。

 ## 边缘情况

 一串全部`0`s 处理得很干净，因为 DP 永远不会增加选定的数量`1`s，因此每个状态保持独立，算法简化为每个索引的局部最大化。 

一串全部`1`s 永远不会触发反转惩罚，因此每个状态转换都是纯粹累加的。 DP 退化为选定的简单累加`1`没有任何跨州干扰，最好的结果对应于每个位置独立选择红色或蓝色。 

单个交替模式，例如`101010`强调增长的 DP 国家和萎缩的 DP 国家之间的相互作用。 每个`1`增加状态维度，而每个`0`立即惩罚所有现有状态，这正是 DP 公式中的转换规则捕获的行为。
