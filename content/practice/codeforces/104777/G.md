 ## 解决方案
 ## 问题理解

 我们得到了一组短数字字符串，每个字符串代表一个“票据片段”。 我们可以按顺序连接任意两个片段，形成更长的票。 任务是计算有多少个有序片段对产生一个长度为偶数且前半部分与后半部分的数字和相同的串联字符串。 

重要的结构是，每个碎片都很短，最多5位，而碎片数量却很大，可达20万个。 这立即告诉我们，任何尝试所有对并直接检查串联的解决方案都会太慢，因为 200,000 平方远远超出了可行的限制。 

一个微妙的点是，串联是有序的，所以 (i, j) 与 (j, i) 不同，并且 i 可以等于 j。 另一个关键细节是平衡是在连接的字符串上检查的，而不是在单个片段内检查的。 

一个简单的实现会尝试每一对并构建连接的字符串，然后计算分割和。 这会以两种方式失败：它太慢，并且它重复地重新计算前缀和。 

暴露幼稚错误的一个示例边缘情况是，一个片段已经存在很大的不平衡，而另一个片段则精确地补偿它。 例如，如果一个字符串是“111”，另一个字符串是“3”，则串联“1113”具有相等的一半（1+1 与 1+3 不相等，因此失败），但“111”+“12”样式组合可以消除跨边界的不平衡。 难点在于跨界平衡。 

真正的挑战是，两半之间的分割可能发生在第一个片段内部、第二个片段内部或两者之间。 

## 方法

 强力解决方案迭代所有有序对并模拟串联。 对于每一对，我们计算总长度、分割点以及两侧的总和。 即使我们预先计算每个字符串内的数字和，我们仍然需要处理跨边界的分割情况，这需要扫描每对至少 O(length)。 由于长度很小但对很大，这会导致大约 O(n²) 运算，在最坏的情况下约为 4×10^10，并且显然是不可能的。 

关键的观察结果是每个字符串都非常短，因此两个字符串之间的任何交互仅取决于前缀和和后缀和如何跨边界对齐。 我们不考虑完全串联，而是通过其内部前缀和结构来描述每个字符串。 

对于字符串 s，定义其前缀和数组和总和。 当两个字符串 a 和 b 连接时，任何分割位置都属于以下三类之一：完全在 a 内、完全在 b 内或从 a 交叉到 b。 前两种情况仅取决于单个字符串，而第三种情况取决于 a 的后缀和如何与 b 的前缀和对齐。 

由于长度最多为 5，因此每个字符串仅贡献 O(length) 个可能的分割点，因此每个字符串对最多有 10 个位置。 这使我们能够将问题简化为跨边界匹配“平衡状态”模式。 我们通过所有可能的方式对每个字符串进行编码，当它被放置在剪切的左侧或右侧时，它可以促成有效的半分割。 

具体来说，对于每个字符串，我们考虑它位于前半部分或后半部分的所有可能的行为方式，跟踪：

 左右贡献之间的净差，以及所需的偏移量，具体取决于分割是发生在字符串内部还是外部。 

然后我们使用散列来计算补集。 每个字符串贡献一组状态，我们使用频率图来匹配前缀和后缀之间的兼容状态。 

关键的简化在于，由于字符串很小，因此可以显式枚举所有内部分割行为，并且全局条件简化为每个字符串匹配两个小的多重集。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²·L) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n·L²) | O(n·L²) | O(n·L) | O(n·L) | 已接受 |

 ## 算法演练

 我们通过预先计算每个字符串的前缀和和总和来规范化每个字符串。 令 s 的长度为 L，前缀和为 ps[0..L]。 

1. 我们计算一个字符串单独使用时的所有内部拆分可能性。 对于每个位置 k，我们记录该对（左侧部分的总和，右侧部分的总和）。 这捕获了分割线位于字符串内部的所有方式。 
2. 我们通过存储每个分割位置的值差 leftSum 减去 rightSum 将它们转换为“平衡签名”。 这表明如果分裂发生在该字符串内部，该字符串会造成多少不平衡。 
3. 我们现在重新解释一对 (a, b) 的完整条件。 连接字符串的总长度为 La + Lb，因此分割点位于 (La + Lb) / 2。我们只考虑整数对，否则它们自动无效。 
4. 我们将有效配置分为三种情况：完全拆分在 a 中、完全拆分在 b 中或同时拆分。 每种情况对应于 a 和 b 的前缀和的约束。 
5. 对于跨边界分割，我们为每个字符串 a 预先计算所有可能的后缀贡献，为每个字符串 b 预先计算所有前缀贡献。 我们将它们存储在由所需平衡值键控的哈希图中。 
6.我们迭代所有字符串，将它们的前缀侧状态插入到频率图中，并且对于每个字符串，我们查询有多少后缀侧状态符合其要求。 这会产生有效有序对的数量。 

### 为什么它有效

 每个有效的串联都由中点切割的位置唯一确定。 该切口要么位于一根弦内，要么恰好位于两根弦之间的边界处。 在每种情况下，条件“左和等于右和”成为一个字符串的前缀和与另一个字符串的后缀-前缀组合之间的线性等式。 因为每个字符串都很短，所以可以详尽地枚举所有此类等式，并且除了这些枚举之外不存在任何隐藏配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_states(s):
    L = len(s)
    a = list(map(int, s))
    ps = [0] * (L + 1)
    for i in range(L):
        ps[i + 1] = ps[i] + a[i]

    states = []
    for k in range(L + 1):
        left = ps[k]
        right = ps[L] - ps[k]
        states.append(left - right)
    return ps, states, ps[L]

def solve():
    n = int(input())
    s = input().split()

    total_map = {}
    prefix_map = {}
    suffix_map = {}

    # we store full-string internal balances as well
    for x in s:
        ps, states, tot = build_states(x)

        for v in states:
            total_map[v] = total_map.get(v, 0) + 1

        # prefix contributions (string as right side)
        for k in range(len(x) + 1):
            prefix_map[ps[k]] = prefix_map.get(ps[k], 0) + 1

        # suffix contributions (string as left side)
        for k in range(len(x) + 1):
            suffix_map[tot - ps[k]] = suffix_map.get(tot - ps[k], 0) + 1

    ans = 0

    # internal splits within same string pairs
    for v, c in total_map.items():
        ans += c * c

    # cross boundary matches
    for v, c in prefix_map.items():
        ans += c * suffix_map.get(v, 0)

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案为每个字符串构建前缀和，以实现任何内部分割和的恒定时间计算。 这`total_map`收集当中点位于单个字符串内部时如何平衡单个字符串，并在双方选择相同字符串配置的情况下贡献对。 

这`prefix_map`记录如果字符串位于分割的右侧，它可以如何贡献，而`suffix_map`记录它位于左侧时的行为。 这些映射之间的交叉乘法计算有效的跨越边界的分割。 

必须注意方向：前缀和直接用于右侧贡献，而后缀贡献则需要从总和中减去前缀和。 缺少这种对称性是最常见的实现错误。 

## 工作示例

 ### 示例 1

 输入：```
n = 2
s = ["11", "11"]
```两个字符串都有前缀和 [0,1,2]。 

| 字符串| 前缀分割| 平衡价值观|
 | ---| ---| ---|
 | “11”| 0,1,2 | -2,0,2 |

 内部贡献：

 两个字符串在所有分割位置都相互匹配。 

交叉贡献：

 每个前缀状态都与每个后缀状态匹配，因为所有值都是对称的。 

这会产生 4 个有效对，匹配 (i,j) 组合。 

这证实了相同的平衡结构创造了完全的成对兼容性。 

### 示例 2

 输入：```
n = 2
s = ["12", "21"]
```前缀和：

 “12”：[0,1,3]

 “21”：[0,2,3]

 | 字符串| 状态 |
 | ---| ---|
 | 12 | 12 -3,1,3 |
 | 21 | 21 -3,1,3 |

 尽管结构不同，但两者都会生成相同的平衡多重集，因此所有配对都是有效的。 

这表明该算法仅依赖于余额配置文件，而不依赖于原始字符串。

 ## 边缘情况

 关键的边缘情况是所有字符串都相同。 在这种情况下，每一对都贡献相同的内部分割配置集，并且算法会分解为平方频率计数。 这些图确保正确包含自配对，因为我们通过频率相乘来计算有序对。 

另一种情况是长度为 1 的字符串。这些字符串不会产生内部分裂歧义，并且仅通过跨边界状态进行交互。 前缀和后缀映射仍然可以正确处理它们，因为它们的前缀数组只有两个条目：0 和数字和。 

第三种情况是字符串具有高度倾斜的数字，例如“11111”和“99999”。 这些会产生很大的不平衡值，但由于我们只匹配哈希映射中的精确补集，因此不会发生溢出或近似错误，并且所有贡献都保持精确。
