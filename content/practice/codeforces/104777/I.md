 ## 解决方案
 ## 问题理解

 给定一个 2n 个整数的数组，我们的任务是将这些数字转换为平面上的 n 个几何点。 每个点必须使用数组中的两个数字，一个作为其 x 坐标，一个作为其 y 坐标，因此每个数组元素在所有点上仅使用一次。 

形成点后，我们必须选择一条至少访问所有点一次的步行。 步行是一条路径，因此它有起点和终点，并且我们可以重新访问点。 两点之间移动的成本是曼哈顿距离，即它们的 x 和 y 坐标的绝对差之和。 目标是最小化这条路径的总长度，同时选择如何将数字配对成点。 

一个关键的结构约束是我们不仅仅优化固定点上的路径。 我们同时决定如何将数字与坐标配对以及如何对路径中的结果点进行排序。 这种耦合就是困难所在。 

约束很小，n 最多为 100，因此 2n 最多为 200。这排除了直接对配对进行指数搜索，因为将 200 个元素划分为对的方法数量是天文数字。 除非是严格结构化的，否则即使是基于子集的动态编程也将是边缘性的。 这强烈表明该解决方案必须依赖于排序结构和贪婪或建设性配对。 

当所有数字都相等时，会出现微妙的边缘情况。 任何配对都会产生相同的点，并且任何路径的长度都为零。 幼稚的方法可能仍会尝试构建复杂的排序，但最佳答案几乎为零。 

另一种角点情况是最佳配对产生重复点时。 由于相等的点之间的距离为零，因此忽略重复问题或假设所有点必须不同的解决方案将是不正确的。 

## 方法

 如果我们暂时忽略配对限制并假设点已经给定，那么最小化访问曼哈顿度量中所有点的路径的最佳方法就是以单调遍历的方式对它们进行排序。 在一个维度上，这很简单：对点进行排序并从一个极端走到另一个极端。 在二维中，曼哈顿距离允许沿轴的可分离性，因此最佳结构通常是通过按一个坐标或配对极值排序而产生的。 

蛮力的想法是将 2n 个数字的所有可能配对枚举为 n 对，然后对于每个配对枚举结果点的所有排列，计算最佳路径（其本身并不平凡，但可简化为排序极端），并取最小值。 这是不可行的，因为配对的数量是 (2n)！ / (2^n n!)，对于 n = 100 而言，这远远超出了任何计算极限。 

关键的见解是分离关注点：我们不应该独立处理每一对，而应该考虑坐标在曼哈顿距离中如何相互作用。 两点 (x1, y1) 和 (x2, y2) 之间的距离分解为 |x1 − x2| + |y1 − y2|，这表明两个坐标应该独立构建，以便在正确排序时允许伸缩总和。 

关键的观察是，曼哈顿度量中的点上的最佳路径可以表现得像对排序结构的遍历，其中每个坐标都贡献受控的总变化。 这促使构造点，以便它们的 x 和 y 值来自排序数组中的极端配对。 一旦我们对数组进行排序，将最小的与最大的、第二小的与第二大的配对，依此类推，可确保每个坐标差得到最大程度的结构化，并且可以安排任何路径以按照精确累积预期伸缩差的顺序遍历点。

这样做的更深层次原因是，​​在曼哈顿空间中，最小化必须覆盖所有点的路径相当于控制两个维度的总变化，而配对极端则最小化了创建不必要的弯路的自由。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解配对和路径 | O((2n)! ) | O((2n)! ) | O(n) | 太慢了|
 | 贪婪地对极端进行排序和配对 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 ### 逐步构建

 1. 对数组a进行非降序排序。 排序暴露了值的全局结构，因此极端配对变得有意义。 如果没有排序，任何贪婪的配对都是没有道理的。 
2. 将最小的元素与最大的元素配对，将第二小的元素与第二大的元素配对，并继续向内。 为 i 从 0 到 n−1 形成 n 个点 (a[i], a[2n−1−i])。 这种结构迫使每个坐标跨越很宽的范围，这对于以结构化方式控制曼哈顿距离至关重要。 
3. 以任意顺序输出这n个点，因为总是可以安排最优路径以与排序配对一致的单调序列访问它们。 排序自由允许我们明确地忽略路径构造。 
4. 由此产生的配置已经达到了曼哈顿距离下可能的最小总路径长度，因此我们不需要显式地构建步行。 

### 为什么它有效

 关键属性是任何有效的解决方案都对应于选择 2n 个值并将它们分组为对，这会产生 x 和 y 坐标的两个大小为 n 的多重集。 任何遍历之间的总曼哈顿成本取决于可以对这些坐标进行多少排序以减少累积绝对差异。 

将最小与最大配对可以最大限度地减少在任一坐标方向上创建不对称分布的能力。 与此配对的任何偏差都会引入一种情况，即两个中间值配对在一起而极值分开，这会增加至少一个坐标中的可能跨度，而不会补偿另一个坐标中的减少。 

这种贪婪配对强制采用一种结构，其中每个大值都由一个小值“平衡”，从而最小化任何路径排序可以利用的最大扩展。 由于曼哈顿距离在坐标上是相加的，因此防止 x 和 y 中的独立膨胀同时保证了全局最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort()
    
    pts = []
    for i in range(n):
        x = a[i]
        y = a[2*n - 1 - i]
        pts.append((x, y))
    
    # Any order is acceptable
    total = 0
    for i in range(n - 1):
        total += abs(pts[i][0] - pts[i+1][0]) + abs(pts[i][1] - pts[i+1][1])
    
    print(total)
    for x, y in pts:
        print(x, y)

if __name__ == "__main__":
    solve()
```该实现首先对数组进行排序，这对于公开配对中使用的极值结构是必要的。 然后它从排序列表的两端对称地构建对。 计算出的`total`对应于构造顺序中的简单遍历，这已经足够了，因为构造保证没有替代排序可以提高总成本。 

一个微妙的点是，我们永远不需要显式优化所有排列之间的路径排序。 该构造确保贪婪排序已经实现了最优结构，因此评估单次遍历就足够了。

 输入：```

```排序后的数组变为`[1, 5, 10, 15]`。 

我们结对：

 (1, 15) 和 (5, 10)。 

现在我们按此顺序计算遍历成本。 

| 步骤| 当前点 | 下一点| dx | 迪 | 成本|
 | --- | --- | --- | --- | --- | --- |
 | 1 | (1, 15) | (5, 10) | 4 | 5 | 9 |

 总成本为9。 

这表明配对极端会迫使一个坐标缩小，而另一个坐标扩大，但以一种受控的方式避免额外的弯路。

 ## 边缘情况

 当所有值都相同时，排序会产生一个统一的数组，并且每一对都成为相同的点。 该算法输出零成本转换，因为每个曼哈顿距离都为零，与最佳答案匹配。 

当值严格增加时，配对会产生对称极值，例如（最小，最大），这确保没有配对会引入不必要的不​​平衡。 构造的遍历仍然产生尽可能小的差异累积，因为每一步都尽可能均匀地消除坐标变化。 

当数组中间存在重复项时，它们也会对称配对。 这可以创建像 (20, 20) 这样的重复点，但重复点不会增加成本，也不会违反约束，因此算法自然会吸收它们，无需特殊处理。
