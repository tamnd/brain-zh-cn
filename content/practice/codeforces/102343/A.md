 ## 解决方案
 ## 问题理解

 该问题要求我们根据每个成员在夏季解决的问题数量，在团队成员之间分配固定的奖池。 如果团队总共解决了 (S) 个问题，奖金池为 (D) 美元，则每个解决的问题价值 (D/S) 美元。 输入保证该值是一个整数，因此每个成员的奖励就是他们解决的问题数乘以一个问题的共同值。 所需的输出是每个团队成员一份奖励，与输入的顺序相同。 

例如，如果奖池为1000美元，成员们解决了5、8、7个问题，则总共解决了20个问题。 每题价值 50 美元，奖励分别为 250 美元、400 美元和 350 美元。 

原题有(1 \le n \le 30)，奖金金额最多为30,000，每个成员解决1到300个问题。 这些界限很小，因此即使是 (O(n^2)) 解决方案也最多执行几百个基本操作。 尽管如此，自然的解决方案是 (O(n))，并且认识到为什么只需要一个总和是这里有用的想法。 官方比赛规定了 1 秒的时间限制和 256 MB 的内存限制。 

有一些小情况可能会暴露粗心的实现。 与一名成员一起，例如```
1 300
5
```唯一的成员必须收到全部 300 美元，因此输出为```
300
```如果解决方案不小心将奖金除以成员数量而不是已解决问题的数量，则会产生错误的结果。 

另一个边界情况是每个成员解决相同数量的问题：```
3 900
10
10
10
```总数为 30，因此每个问题价值 30 美元，每个成员收到 300 美元。输出为```
300
300
300
```使用当前成员已解决问题的数量作为分母来独立计算每个奖励的粗心解决方案将会失败，因为分母必须是已解决问题的总数。 

可分割性保证也很重要。 为了```
2 100
3
7
```已解决的问题总数为 10，因此每个问题的价值恰好为 10 美元，正确的输出为```
30
70
```在此示例中，使用浮点除法可以在数值上起作用，但整数除法直接代表问题的保证，并避免引入不必要的舍入问题。 

## 方法

 最直接的暴力方法是分别计算每个成员已解决问题的总数。 对于成员 (i)，我们可以扫描所有 (n) 个成员，添加他们解决问题的数量，将奖金池除以该总数，然后乘以第 (i) 个成员的数量。 这是正确的，因为每个成员使用的已解决问题总数与分母完全相同。 

这种方法的问题是重复工作。 每个成员的总和都是相同的，但暴力实现会一次又一次地计算它。 对于 (n=30)，这意味着在最坏的情况下最多可添加 (30 × 30 = 900)，这对于这些约束来说仍然足够快。 它的弱点是概念性的而非实践性的：它忽略了每个答案都共享分母的事实。 

关键的观察结果是，已解决问题的总数是一个全局值。 我们可以读取所有成员计数一次，计算一次总和，然后使用相同的每个问题值计算每个成员的奖励。 如果 (S) 是已解决问题的总数，则一个已解决问题的值是

 [
 \text{值} = \left\lfloor\frac{D}{S}\right\rfloor。 
]

 该语句保证 (D/S) 是一个整数，因此向下取整操作不会丢弃任何内容。 每个解决 (a_i) 个问题的成员都会收到

 [
 a_i \times \text{值}。 
]

 蛮力之所以有效，是因为它最终为每个成员找到相同的全局总和，但无法重用它。 通过观察总和是共享的，我们可以将计算减少到一次计算总和和一次计算奖励。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(n^2)) | (O(n)) | (O(n)) | 接受这些限制，但不必要的重复工作|
 | 最佳 | (O(n)) | (O(n)) | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1. 读取 (n)，团队成员人数，以及 (D)，总奖金。 这两个值决定了团队的规模以及最终必须分配的金额。 
2. 读取每个团队成员已解决问题的数量并将这些值存储在数组中。 同时，累加他们的总和（S），因为每个成员的奖励使用相同的已解决问题总数。 
3. 计算`money_per_problem = D // S`。 该问题保证除法是精确的，因此整数除法给出了与一个已解决的问题相关的精确奖励。 
4. 对于每个解决了 (a_i) 个问题的成员，计算`a_i * money_per_problem`。 这直接遵循奖励与解决问题的数量成正比的规则。 
5. 按输入顺序打印结果奖励，每行一个。 保持原始顺序很重要，因为每个输出行都对应于相应的团队成员。 

### 为什么它有效

 不变的是，读取到目前为止已处理的成员后，累加的总和正是这些成员解决的问题数。 当所有（n）个成员都被读取后，总和就是已解决问题的总数（S）。 由于每一美元的奖励与解决的问题成正比，因此一个问题的常见奖励是（D/S）。 问题保证这个值是一个整数，所以`D // S`是准确的。 将共同价值乘以每个成员解决的问题数，就可以得出该成员的奖励份额。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, money = map(int, input().split())

    solved = []
    total = 0

    for _ in range(n):
        x = int(input())
        solved.append(x)
        total += x

    money_per_problem = money // total

    for x in solved:
        print(x * money_per_problem)

if __name__ == "__main__":
    solve()
```第一个循环对应于输入读取和总体构建步骤。 存储这些值是必要的，因为只有知道已解决问题的总数才能打印奖励。 

循环结束后，`money // total`计算解决一个问题的奖励。 整数除法是经过深思熟虑的，因为输入保证了精确的整除性。 

第二个循环将公共的每个问题奖励应用于每个成员的解决计数。 不存在差一问题，因为循环恰好运行 (n) 次，每个成员运行一次。 

Python 整数具有任意精度，因此即使值大于原始约束，也不存在整数溢出问题。 输出每行产生一个成员，与所需的格式匹配。

 ## 边缘情况

 对于单个团队成员，输入```
