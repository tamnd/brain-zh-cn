 ## 解决方案
 ## 问题理解

 我们得到一个仅包含小写英文字母的非空字符串。 任务是重新排列其字符，以便频率较高的字符在结果中出现得更早。 当两个字符出现的次数相同时，按字母顺序排列较小的字符必须排在前面。 原始字符串中的每个匹配项都必须保留在输出中，因此我们仅更改字符的顺序。 

例如，字符串`dcbbdabb`包含四个`b`字符，两个`d`人物，一`a`，和一个`c`。 因此频率排序为`b`,`d`， 然后`a`和`c`， 和`a`前`c`因为它们的频率相等。 所需的结果是`bbbbddac`。 最初的问题限制输入字符串为 70 个小写字母，Codeforces 版本有 1 秒的时间限制和 256 MB 的内存限制。 

70 的小界限意味着即使 O(n²) 解决方案也最多执行 4900 个基本字符比较，因此简单的实现已经足够快了。 尽管如此，问题的结构为我们提供了一个 O(n) 的解决方案，并且需要固定数量的额外工作。 关键是只有 26 个可能的字符，因此我们永远不需要发现或排序任意值的集合。 

有几种边缘情况可能会导致实现产生错误的顺序。 如果每个字符都不同，如`abc`，每个频率都是一，所以字母顺序决定一切，输出是`abc`。 保留原始顺序而不是应用平局断路器的解决方案将在输入上失败，例如`cba`，其正确输出是`abc`。 

字母表中分隔的字符之间也可能出现相同的频率。 为了`programming`，频率是`g=2`,`m=2`，以及其中的每个字符`a`,`i`,`n`,`o`,`p`,`r`发生一次。 正确的输出是`ggmmainopr`仅当字母在每个频率组内排序正确时，但实际样本输出是`ggmmrrainop`因为`r`也会出现两次。 因此完整的频率排序是`g`,`m`,`r`， 其次是`a`,`i`,`n`,`o`,`p`, 给予`ggmmrrainop`。 仅计算某些出现次数或使用原始字符顺序进行联系的粗心实现将在此处失败。 

另一种边界情况是仅包含一个不同字符的字符串，例如`aaaaa`。 它的频率是五，并且没有竞争字符，所以答案必须保留`aaaaa`。 如果实现意外地为每个不同字符创建一个输出副本而不是每次出现一个副本，则会产生错误的长度。 

## 方法

 直接的暴力解决方案可以单独处理每个字符。 对于输入字符串中的每个位置，扫描整个字符串并计算该字符出现的次数。 获得每个字符的频率后，按照频率降序和字母升序对字符进行排序，然后将每个字符写入与其频率相同的次数。 这是正确的，因为在执行最终排序之前，每个字符都被分配了其确切的全局频率。 

如果输入的长度为 n，并且我们独立扫描每个位置的所有 n 个位置，则频率计数阶段将执行 O(n²) 字符检查。 在实际约束n≤70下，最坏的情况也只有70²=4900次检查，所以这个暴力版本还是很容易被接受的。 在官方约束下不存在现实的性能问题。 然而，如果同样的方法应用于 n = 100000，则需要 10^10 次检查，这远远超出了 1 秒竞赛程序可以处理的范围。 

使更好的解决方案变得简单的观察结果是，每个字符都属于仅有的 26 个小写字母类别之一。 我们可以用长度为 26 的数组一次计算所有频率。一旦知道这些计数，我们只需要检查字母表`a`通过`z`。 频率决定了主要排序，因此我们可以收集 26 个字符并对这些字符对进行排序`(-frequency, character)`。 因为 26 是一个常数，所以该排序步骤相对于输入长度需要恒定的时间。 

这两种方法的主要区别在于它们执行的重复工作量。 蛮力方法反复重新发现本来可以存储的频率，而最优方法记录每个频率一次，然后对固定字母表进行操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(26) | 接受 n ≤ 70 |
 | 最佳| O(n + 26 log 26) = O(n) | O(n + 26 log 26) = O(n) | O(26) | 已接受 |

 ## 算法演练

 1.读取单个输入字符串并创建长度为26的频率数组。索引`0`代表`a`， 指数`1`代表`b`，依此类推通过`z`。 固定数组就足够了，因为输入字母表是预先知道的。 
2. 遍历字符串中的每个字符并增加其对应的频率。 对于一个角色`ch`，其数组位置为`ord(ch) - ord('a')`。 此遍之后，频率数组包含构建答案所需的完整信息。 
3. 为小写字母创建 26 个字符频率对。 频率为零的字符可以暂时留在集合中，因为它们对输出没有任何贡献。 
4. 按频率递减对这些对进行排序，当频率相等时，按特征递增排序。 在Python中这可以直接用key来表示`(-frequency, character)`。 负频率反转通常的升序数字顺序，而字符保持正常的字母顺序。 
5. 根据出现的频率重复每个字符来构建答案。 频率为零的字符自然会贡献一个空字符串，因此包含零频率条目不会改变结果。 
6. 打印结果字符串，不带空格。 每个原始事件都只发出一次，因此输出的长度与输入的长度完全相同。 

### 为什么它有效

 计数结束后，不变量是`freq[i]`等于索引表示的字符出现的确切次数`i`在输入中。 通过降低频率对字符频率对进行排序，将每个字符置于频率较小的所有字符之前。 对于频率相同的对，辅助键是字符本身，因此它们按字母顺序显示。 最后，准确地重复每个字符`freq[i]`times 保留输入中的每一次出现。 因此，生成的字符串既满足排序规则，又完全包含原始的多重字符集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    freq = [0] * 26

    for ch in s:
        freq[ord(ch) - ord('a')] += 1

    chars = []
    for i in range(26):
        ch = chr(ord('a') + i)
        chars.append((ch, freq[i]))

    chars.sort(key=lambda item: (-item[1], item[0]))

    ans = []
    for ch, count in chars:
        ans.append(ch * count)

    print(''.join(ans))

if __name__ == "__main__":
    solve()
```第一部分正好读取一行，因为该问题包含一个字符串而不是多个测试用例。 呼唤`strip()`删除尾随换行符而不更改任何有效的输入字符，因为输入仅包含小写字母。 

频率数组的索引为`ord(ch) - ord('a')`。 例如，`ord('a') - ord('a')`为零并且`ord('z') - ord('a')`是 25，因此每个可能的输入字符都映射到有效的数组位置。 

对列表存储字符及其计数。 排序键`(-item[1], item[0])`在一个表达式中实现两个必需的规则。 第一个组件将频率较高的字符放在前面，而第二个组件则将频率相同的字符按字母顺序排列。 

答案会累积在列表中，而不是重复连接字符串。 每个乘法例如`ch * count`创建一个角色的所有副本，并且`''.join(ans)`将各个部分组合一次。 只有 26 块，因此简单高效。 

Python 中不存在整数溢出问题。 最大频率只是输入的长度，在原始约束下最多为70。

 ## 边缘情况

 单字符案例`z`通过计算索引 25 处的一次出现来处理。所有其他频率均为零，因此对位置进行排序`z`首先，输出结构恰好发出一个`z`。 结果是`z`。 

对于全相等的字符串，例如`aaaaa`，频率数组包含`freq[a] = 5`其他地方都是零。 排序后的对放入`a`首先因为它具有唯一的正频率，并且该结构发射`a * 5`, 生产`aaaaa`。 没有字符丢失或重复。 

领带盒`cba`执行次要排序规则。 所有三个字符的频率均为一，因此它们的频率无法区分它们。 排序后的键是`(−1, a)`,`(−1, b)`， 和`(−1, c)`, 给予`abc`。 依赖输入顺序的实现将错误地返回`cba`。 

最大大小的情况包含频率为 35、20、10 和 5 的 70 个字符。计数过程记录这四个频率，排序阶段按频率降序排列字符，然后重建再次生成所有 70 个字符。 由于频率数组的大小固定为 26，因此将输入从一个字符增加到最大大小只会改变计数工作，而不会改变辅助存储器。 

多重领带的情况`zzzyyxxwwvvvuu`有`z=3`,`v=3`,`y=2`,`x=2`,`w=2`， 和`u=2`。 两个频率三字符的顺序为`v`,`z`，而频率两个字符的顺序为`u`,`w`,`x`,`y`。 该算法因此产生`vvvzzzuuwwxxyy`。 此案例直接检查字母顺序是否在每个频率组内独立应用。
