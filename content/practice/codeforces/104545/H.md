 ## 解决方案
 ## 问题理解

 我们正在模拟一个涉及英雄和一系列怪物的连续战斗过程。 英雄以初始力量值开始，然后按照固定的顺序一一遭遇怪物。 每个怪物都有一个力量值。 当英雄遇到怪物时，只有自己当前的力量至少等于怪物的力量，才能击败它。 如果他赢了，他的力量就会增加那只怪物的力量。 如果他遇到了无法击败的怪物，这个过程就会立即停止。 

任务是确定英雄是否能够从他的初始力量开始，成功地击败给定序列中的每个怪物。 

输入大小最多允许 100,000 个怪物。 这立即表明任何涉及嵌套循环或多次重复扫描列表的方法都会太慢。 对怪物进行一次线性传递是必要的，因为 O(N²) 操作将远远超出可接受的限制。 

当根本没有怪物时，就会出现一种微妙的边缘情况。 在这种情况下，无论英雄的初始力量如何，他都会成功。 当英雄的初始力量为零时，会出现另一个极端情况。 如果第一个怪物的强度为正，则英雄根本无法继续前进，并且答案将变为否定，除非第一个怪物的强度也为零。 这种零强度交互很重要，因为它不会打破单调累积行为，但会影响提前终止决策。 

## 方法

 蛮力解释已经非常接近实际模拟。 我们按顺序迭代怪物，每一步检查当前英雄的力量是否足够。 如果是，我们将怪物的力量添加到英雄的力量中并继续。 如果没有，我们立即断定失败。 

这种直接模拟是正确的，因为规则明确定义了确定性过程，没有选择或替代策略。 无法重新排序战斗或跳过怪物，因此状态演变是固定的。 

天真的担忧是，如果英雄后来失败了，我们是否需要重新考虑之前的决定或尝试回溯。 这种直觉在这里并不适用，因为一旦英雄击败怪物，他的力量只会增加。 没有任何机制可以降低功率或引入分支状态。 结果，模拟已经是最优的。 

唯一有意义的优化见解是认识到不需要排序、贪婪重排或预处理。 输入顺序是固定的，必须严格遵循，因此解决方案是带有条件检查的纯线性累加。

 ## 算法演练

 1. 读取怪物数量 N 和初始英雄力量 H。这定义了任何交互发生之前模拟的起始状态。 
2. 按给定顺序迭代每个怪物的强度。 顺序很重要，因为英雄无法选择先对抗哪个怪物。 
3.对于每个怪物，将其力量与当前英雄力量进行比较。 如果英雄的力量严格小于怪物的力量，则立即终止并输出失败。 
4.如果英雄能够击败怪物，则通过增加怪物的力量来增加他的力量。 这模拟了击败怪物永久增强英雄的规则。 
5. 继续此过程，直到处理完所有怪物或发生失败。 
6. 如果循环完成且没有失败，则输出成功。 

### 为什么它有效

关键的不变量是，在成功处理第 i 个怪物后，英雄的力量恰好等于初始力量加上迄今为止所有击败的怪物的力量总和。 由于每次成功的战斗都会严格保留之前所有的力量增益，并且只增加正值，因此英雄的力量是单调非递减的。 这保证了一旦怪物在其回合中被击败，就不会有任何早期的隐藏条件可能使未来的比较无效。 因此，模拟准确地反映了问题的定义，遇到的任何故障都是最早可能的故障点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, h = map(int, input().split())
    if n == 0:
        print("SIM")
        return

    monsters = list(map(int, input().split()))

    for f in monsters:
        if h < f:
            print("NAO")
            return
        h += f

    print("SIM")

if __name__ == "__main__":
    solve()
```该实现直接对逐步模拟进行编码。 支票`if n == 0`显式处理空序列，因为不需要比较并且英雄很容易成功。 

在循环内部，比较`h < f`捕获失败条件。 如果触发了，我们会立即停止处理，因为一旦失败，后面的怪物就无关紧要了。 否则，我们会将怪物的力量积累到`h`，它模拟了永久功率增益。 

不需要额外的数据结构，因为状态仅取决于当前功率值。

 ## 边缘情况

 一种重要的边缘情况是没有怪物时。 输入是`0 H`。 算法读取`n = 0`并立即输出成功，而不尝试读取或处理第二行。 这可以防止不必要的输入解析并避免边缘索引错误。 

另一种情况是英雄以零力量开始。 对于输入：```
3 0
0 0 1
```模拟过程如下。 第一个怪物是0，所以`h < f`为 false，power 保持为 0。第二个也是 0，仍然可以。 到了第三个怪物的时候，`0 < 1`触发失败。 该算法可以正确识别第一个不可能的战斗，而无需跳过或重新排序。 

第三种情况是所有怪物都为零的情况。 例如：```
4 0
0 0 0 0
```自此以后每次比较都通过`h >= f`总是成立。 英雄的力量保持不变，但过程永远不会失败，并取得成功。
