 ## 解决方案
 ## 问题理解

 我们得到了不断变化的“统计数据”集合，其中每一个都要么是正确的，要么是错误的。 最初有`v`真实的统计数据和`f`虚假统计数据。 感兴趣的关键数量是所有统计数据中错误统计数据的比例。 

有一种特殊的操作可以多次应用。 每次我们应用它时，我们都会考虑“超过 75% 的统计数据是错误的”这一说法。 这个陈述本身就成为一个新的统计数据，其真值取决于流动比率`f / (v + f)`。 

如果当前错误统计的比例严格大于 3/4，则该陈述被认为是正确的，我们增加`v`乘以 1。否则，我们增加`f`减1。每次操作后，统计总数加1，真假之间的分布根据是否超过阈值而变化。 

我们必须确定必须应用此操作多少次，直到错误统计的比例恰好达到 75%，这意味着`f / (v + f) = 3/4`。 

约束允许最多`10^5`测试用例的值高达`10^8`。 这排除了在最坏情况下为每个操作逐步重新计算分数的任何模拟，因为该过程可能会花费每次测试的线性时间并累积到不可行的总数。 

简单的模拟还隐藏了一个结构性陷阱：决策的翻转取决于比率是高于还是低于 3/4，这意味着更新序列在明显变量中不是单调的。 如果我们尝试迭代直到收敛，我们很容易错误地处理不等式切换行为的边界。 

一个小的说明性边缘情况是`v = 1, f = 2`。 比例为`2/3`，低于3/4，所以运算增加`f`。 盲目地重复会以一种快速漂移而没有明显收敛的方式改变系统。 粗心的模拟可能会假设收敛是立即的或单调地趋向于目标比率，但这在结构上是没有保证的。 

真正的挑战是我们不需要模拟该过程，而是确定达到精确代数条件所需的确切步骤数。 

## 方法

 直接方法将逐步模拟该过程。 每一步都需要检查是否`f / (v + f) > 3/4`，更新任一`v`或者`f`，并继续直到满足相等条件。 虽然每个步骤都是 O(1)，但步骤数可能会很大，因为`v`和`f`可以增长到分数恰好稳定在 3/4 的点。 在最坏的情况下，这可能需要与系统最终大小成比例的大量操作，而系统的最终大小不受小常数的严格限制。 

关键的观察是每个操作都不是任意的，它总是沿着两个确定性线性方向之一移动状态`(v, f)`飞机。 条件`f / (v + f) > 3/4`相当于`4f > 3(v + f)`，这简化为`f > 3v`。 所以决策规则只取决于是否`f`大于`3v`。 

这将过程分为两个状态。 如果`f > 3v`，我们增加`v`。 否则我们增加`f`。 每个操作都会改变`v`或者`f`恰好为 1，因此系统沿着分段线性路径演化。 

我们可以推断需要多少次操作才能达到精确的平衡条件，而不是模拟每一步`f = 3(v + f)/4`，这简化为`4f = 3(v + f)`并进一步`f = 3v`。 所以目标是达到这样的状态`f = 3v`。 

我们可以把这个过程理解为反复调整`(v, f)`直到满足这个线性约束。 每个操作要么增加`v`或增加`f`，我们想要计算需要多少增量才能准确落在线上`f = 3v`。 

这变成了一个确定性算术问题：我们跟踪当前状态距离满足有多远`f = 3v`，并且每次操作都会以受控的方式将其拉近。

 | --- | --- | --- | --- |
 | 模拟 | O（答案）| O(1) | O(1) | 太慢了 |
 | 算术构造| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们重新表述条件并导出所需步骤数的直接表达式。 

1、从目标条件的身份出发`f = 3v`。 这来自重写`f / (v + f) = 3/4`，这减少到`4f = 3v + 3f`， 因此`f = 3v`。 
2. 观察操作如何根据之间的不等式进行表现`f`和`3v`。 如果`f > 3v`，那么当前分数大于 3/4，因此我们递增`v`。 如果`f ≤ 3v`，我们增加`f`。 这意味着每一步都会使系统朝着平衡差异的方向发展`f - 3v`。 
3. 定义势函数`d = f - 3v`。 目标是`d = 0`。 我们现在重写如何`d`每次操作后都会发生变化。 如果`d > 0`，我们增加`v`，这会转变`d`进入`(f) - 3(v+1) = d - 3`。 如果`d ≤ 0`，我们增加`f`，这会转变`d`进入`(f+1) - 3v = d + 1`。 
4. 我们现在模拟进化`d`不是通过在天真的循环中一步一步地执行，而是通过块跳跃。 什么时候`d`为正数，重复应用每一步将其减少 3，直到变为非正数。 当它为非正数时，重复应用每一步将其增加 1，直到它变为正数。 
5. 该过程在减少阶段和增加阶段之间交替。 每个阶段都可以使用除法分解为直接算术跳转，而不是逐步迭代。 
6. 我们继续这些交替跳跃，直到`d`正好变成0。累积的跳跃次数就是答案。 

它起作用的原因是该过程完全由单个整数状态控制`d = f - 3v`。 每次操作都会发生变化`d`由仅取决于其符号的固定常数。 除此之外没有隐藏状态`d`，因此演化是具有两个线性转换规则的整数上的确定性行走。 折叠重复的相同转换可以保留正确性，因为决策规则在单调段内不会改变`d`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_one(v, f):
    d = f - 3 * v
    steps = 0

    while d != 0:
        if d > 0:
            # apply v increments: each reduces d by 3
            # we need to know how many such steps until d <= 0
            k = (d + 2) // 3
            d -= 3 * k
            v += k
            steps += k
        else:
            # apply f increments: each increases d by 1
            k = (-d)
            d += k
            f += k
            steps += k

    return steps

t = int(input())
out = []
for _ in range(t):
    v, f = map(int, input().split())
    out.append(str(solve_one(v, f)))

print("\n".join(out))
```该实现压缩了长时间运行的相同操作。 什么时候`d > 0`，我们重复应用“增加 v”操作，直到`d`过零或变得足够小，以至于需要少于 -3 步的完整块。 公式`(d + 2) // 3`准确计算 3 需要多少减量才能带来`d`为零或以下。 

什么时候`d ≤ 0`，每一步都增加`d`1，所以我们直接跳过去`-d`步数达到零。 这避免了通过线性增长进行逐一迭代。 

变量`steps`累积执行的操作总数，这就是问题所要求的。 

## 工作示例

 ### 示例 1

 输入：`v = 1, f = 2`我们计算`d = f - 3v = 2 - 3 = -1`。 

| 步骤| d | 行动| k | 新d|
 | --- | --- | --- | --- | --- |
 | 1 | -1 | 增加 f | 1 | 0 |

 该算法看到`d ≤ 0`，所以增加了`f`通过1，使`d = 0`。 该过程一步结束。 这与系统在一次调整后立即达到平衡状态的事实相符。 

### 示例 2

 输入：`v = 2, f = 10`最初的`d = 10 - 6 = 4`。 

| 步相| d 开始 | 行动| k | d 端 |
 | --- | --- | --- | --- | --- |
 | 1 | 4 | 增加v | 2 | -2 |
 | 2 | -2 | 增加 f | 2 | 0 |

 首先我们减少`d`以 3 为一组，直到过零，然后向上补偿。 该过程恰好稳定在`d = 0`。 

这演示了算法如何在减少阶段和增加阶段之间交替，而不需要单步模拟。

 ## 边缘情况

 一种重要的边缘情况是系统恰好在边界上启动`f = 3v`。 在这种情况下，所需的答案为零，因为条件已经满足。 例如，输入`v = 10, f = 30`给出`d = 0`，因此算法立即返回零，而不进入任何循环。 

另一种微妙的情况发生在`f`远小于`3v`。 例如`v = 10, f = 1`给出`d = -29`。 该算法应用单块递增`f`29岁，直接到达`d = 0`。 简单的模拟需要 29 次迭代，但压缩方法可以一次性处理它，从而保持正确性，因为该区域中的每一步都具有相同的行为。
