 ## 解决方案
 ## 问题理解

 我们给出了一个大小为的矩形网格$N \times M$，其中每个单元格代表一个房间。 我们从左上角的单元格开始$(1,1)$并想要到达右下角的单元格$(N,M)$。 移动仅限于通常的网格单调移动，这意味着每一步要么向下移动一个单元格，要么向右移动一个单元格，因此就访问的单元格数量而言，每条有效路线都是最短路径。 

在这个网格内有一个禁止单元格$(X,Y)$不得访问该内容。 任何经过该单元格的路径都是无效的，必须从计数中排除。 任务是计算从开始到结束存在多少条最短路径，同时避开单个阻塞单元。 

限制很小：$1 \le N, M \le 30$。 这立即告诉我们网格对于动态编程或组合学来说足够小。 即使是天真的$O(N \cdot M \cdot 2)$或者$O(N^2 M^2)$方法是可以接受的，但是路径上的任何指数形式都是不必要的。 

当禁止单元格与起点或目的地重合时，会出现微妙的边缘情况。 如果$(X,Y) = (1,1)$，那么根本不存在路径，因为我们立即被阻塞。 如果$(X,Y) = (N,M)$，由于同样的原因，目的地无法到达。 另一个重要的情况是，当被阻塞的单元格位于所有最短路径结构之外时，由于网格边界而无法到达或不相关，但在单调网格中，每个单元格都是可到达的，因此它总是很重要，除非它以一种微不足道的方式位于边缘。 

## 方法

 思考问题最直接的方法就是枚举从$(1,1)$到$(N,M)$，仅向右或向下迈步，并丢弃那些通过的$(X,Y)$。 这在概念上是简单且正确的，因为每条路径都被显式检查，但它在组合上是爆炸性的。 一个单调路径的数量$N \times M$网格是$\binom{N+M-2}{N-1}$，即使对于中等大小，它也会增长得非常快，并且即使在$30 \times 30$。 

关键的观察是，当我们以穿过单元为条件时，每条有效路径都由两个独立的段组成：$(1,1)$到某个单元格，然后从该单元格到$(N,M)$。 这种结构表明动态规划或组合数学。 我们不考虑完整路径，而是计算到达每个单元格的方式，因为每个单元格只能从其顶部或左侧邻居到达。 

禁止单元只是充当屏障，我们强制路径数量为零，并且依赖于它的所有路径在 DP 传播中自然消失。 这将问题转化为具有一种阻塞状态的标准网格路径计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举 |$O(\binom{N+M}{N})$|$O(N+M)$递归深度 | 太慢了 |
 | 动态规划|$O(NM)$|$O(NM)$| 已接受 |

 ## 算法演练

 我们定义一个 DP 表，其中`dp[i][j]`代表到达单元格的方式数$(i,j)$从$(1,1)$不踏入禁闭牢房。 

1. 初始化一个2D数组`dp`尺寸的$N \times M$带零。 这确保了任何未明确到达的单元格在默认情况下仍然无效。 
2. 设置`dp[1][1] = 1`如果起始单元未被禁止，否则答案立即为零。 这锚定了整个 DP，因为所有路径都源自这里。 
3. 按行优先顺序迭代所有单元格。 对于每个单元格$(i,j)$，如果符合禁止位置$(X,Y)$，我们强迫`dp[i][j] = 0`并跳过其中的转换。 这有效地删除了所有经过它的路径。 
4. 如果该单元未被阻塞，则传播来自其有效前辈的贡献：如果$i > 1$， 添加`dp[i-1][j]`，如果$j > 1$， 添加`dp[i][j-1]`。 这些对应于从上方或从左侧到达，这是唯一允许的移动。 
5.填表后答案为`dp[N][M]`，它聚合了所有从未触及禁止单元的有效最短路径。 

这种方法有效的核心原因是，通往单元格的每条有效路径都必须以最后一次移动结束，无论是从上方还是从左侧。 这会创建所有路径的完整且不重叠的分解，确保每条路径在首次到达每个状态时都被精确计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, M, X, Y = map(int, input().split())
    
    if (X, Y) == (1, 1):
        print(0)
        return
    
    dp = [[0] * (M + 1) for _ in range(N + 1)]
    dp[1][1] = 1
    
    for i in range(1, N + 1):
        for j in range(1, M + 1):
            if i == 1 and j == 1:
                continue
            if i == X and j == Y:
                dp[i][j] = 0
                continue
            
            ways = 0
            if i > 1:
                ways += dp[i - 1][j]
            if j > 1:
                ways += dp[i][j - 1]
            dp[i][j] = ways
    
    print(dp[N][M])

if __name__ == "__main__":
    solve()
```DP 表有意采用 1 索引来匹配问题陈述并避免重复的索引移位错误。 在任何转换逻辑应用于禁止单元之前，禁止单元被明确归零，确保它不会对下游状态做出贡献。 

一个微妙的细节是单独处理起始单元。 如果没有这个保护，循环将覆盖`dp[1][1]`或者通过转换错误地重复计算它，特别是在统一基本情况的实现中。

 ## 边缘情况

 当禁区为起始位置时$(1,1)$，DP 立即解析为零，因为甚至没有路径可以开始。 该算法通过提前返回来处理此问题，从而防止不必要的计算。 

当禁区为目的地时$(N,M)$，DP 最终自然会产生零，因为该单元被迫为零并且从不做出贡献。 例如，在一个$2 \times 2$网格与块在$(2,2)$，每条路径都以禁止状态终止，所以`dp[2][2] = 0`。 

当禁止单元格位于边界时，例如$(1,k)$或者$(k,1)$，它只是提前删除一类路径。 DP 仍从剩余方向累积有效替代方案，并且递归确保无效贡献不会泄漏到被阻止的单元格中。
