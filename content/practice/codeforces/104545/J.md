 ## 问题理解

 这个故事描述了一个角色，他在自助餐厅账户上只存了一次钱，然后反复用它来吃饭。 每顿饭的固定费用为两个单位货币。 经过一些未知的用餐次数后，我们观察到两个值：单次充值中添加了多少钱，以及我们检查时的剩余余额。 

任务是重建充值后支付了多少餐费。 关键的隐藏结构是，充值后余额发生变化的唯一方法是重复减去每顿饭的固定成本，因此整个问题简化为找出账户中消失了多少钱，并将其除以一顿饭的价格。 

输入给出两个整数，充值金额和当前余额。 输出是充值后消耗的餐数。 

约束非常小，两个值都以 200 为界，并保证具有相同的奇偶校验。 这立即排除了任何模拟或搜索的需要。 任何在值范围内以恒定时间或线性时间运行的解决方案都已经足够了。 

一个天真的但常见的错误是尝试在充值之前重建未知的初始余额。 例如，人们可能会假设帐户从零开始，或者尝试猜测预充值历史记录。 这是不必要的，因为问题明确指出只有一次充电，所有相关的事情都会在它之后发生。 

另一个潜在的混乱来自奇偶校验约束。 如果没有注意到每顿饭的花费正好是两顿，人们可能会认为平价是一种转移注意力的说法。 实际上，它保证充值和最终余额之间的差异可以被二整除，因此答案始终是整数。 

## 方法

 暴力解释将一一模拟膳食。 从充值金额开始，不断减去二，直到达到最终余额。 这是有效的，因为每个操作直接对应一顿饭，并且我们在达到观察到的平衡时停止。 然而，尽管这里的界限很小，但这种方法在概念上是浪费的，因为它每餐执行一次迭代。 

关键的观察是所有餐点的成本都是相同的。 我们可以直接计算总支出金额，即添加金额与剩余金额之间的差值，而不是模拟重复减法。 该总支出必须等于用餐次数乘以二。 所以答案是通过一次除法得到的。 

这将问题从逐步过程简化为直接算术提取。

 ## 算法演练

 我们计算充值后使用了多少钱，并将其转换为餐数。 

1. 读取两个整数，充值值和当前余额。 这些代表充值后的起始金额和观察到的剩余金额。 
2. 充值金额减去最终余额，计算出总消费金额。 该差异恰好对应于所有餐食的总和，因为没有其他操作影响平衡。 
3. 将花费金额除以二即可得到餐食数量，因为每顿饭正好花费两个单位。 
4. 输出结果。 

### 为什么它有效

单次充值后，唯一可能影响余额的操作是支付餐费，每支付一次，余额正好减少 2。 因此，平衡减少的总量恰好是进餐次数的两倍。 由于没有其他交易发生，初始充值后余额和最终余额之间的差异唯一地确定了餐数。 奇偶校验条件保证该差值始终为偶数，因此整数除法在没有余数的情况下有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())
    spent = x - y
    print(spent // 2)

if __name__ == "__main__":
    solve()
```直接按照推导公式实现。 减法`x - y`捕获充值后的总支出。 不需要循环或模拟，因为每一单位的花费都对应于固定的餐食数量。 

唯一的微妙之处是确保使用整数除法。 由于该问题保证了相同的奇偶性，`x - y`始终是偶数，因此楼层除法可以安全地产生正确的整数结果。

 ## 边缘情况

 当充值等于当前余额时，差值为零，因此算法输出零餐。 这对应于充值后没有发生支出的情况，减法步骤立即产生零。 

当余额为零时，充值的钱就全部被消耗掉了。 该算法计算`x - 0`，等于全额充值金额，除以二即为总用餐次数。 由于奇偶校验约束确保`x`即使在这种情况下，除法始终是精确的并产生有效的整数计数。
