 ## 解决方案
 ## 问题理解

 我们得到了几组物品，其中每组对应于一种颜色的气球并具有初始计数。 容器最多只能容纳固定数量的充气气球，因此我们需要将充气气球的总数减少到最多给定的限制。 

不同之处在于减少是如何运作的。 时间被划分为秒。 在每一秒中，我们只选择一种颜色并观察该颜色的所有气球。 当观察一种颜色一秒钟时，该颜色的所有气球实际上都会减少一半，这个过程就像计数时的地板划分一样。 如果一种颜色有 x 个气球，则经过一次操作后它会变成 ⌊x/2⌋。 我们重复这个过程，每秒选择一种颜色，并且我们希望最小化所需的秒数，直到所有剩余气球的总和最多为 S。 

输入给出颜色数量和容量限制 S，后跟每种颜色的初始计数。 输出是所需的最小操作数（秒）。 

约束允许最多 100,000 种颜色，并且每个计数可以大到 1e9。 这立即排除了任何简单地模拟所有颜色的所有可能操作的方法。 每个操作只影响一种颜色，因此在每个可能的选择之后重复重新计算总和的幼稚策略会太慢，特别是因为单一颜色可能需要 O(log bi) 减少，并且对所有颜色求和给出了大约 1e5 × 30 次操作的潜在上限，但决策过程更重要：选择每秒减少哪种颜色是核心困难。 

当 S 非常小或为零，或者所有值都已经很小时，就会出现边缘情况。 例如，如果 S = 0 并且所有 bi = 1，我们必须将所有内容减少到零，并且每个减少序列都很重要，因为每种颜色都会独立收缩。 另一个边缘情况是当 S 足够大以至于根本不需要任何操作时，它应该立即返回 0。 

## 方法

 蛮力视图是逐步模拟该过程。 我们每一秒都会尝试所有可能的颜色，对一种选定的颜色应用减半操作后计算所得的总和，然后选择最佳选择。 这将涉及在每一步重新计算每种候选颜色的总和。 即使使用预计算，状态数量也会快速增长，因为每个操作都会改变状态空间，并且我们需要模拟大量步骤。 在最坏的情况下，每种颜色可能会减少 log bi 倍，因此可能存在数百万次状态转换，并且每个决策步骤都会花费 O(N)，从而导致不可行的 O(N² log A) 规模行为。 

关键的观察结果是，每个操作都会产生递减效应：将大量数字减少一半最初会产生显着的下降，但随着数字变小，收益也会缩小。 这表明我们应该始终优先考虑当前总和减少最多的操作。 

如果我们从边际增益的角度考虑，每种颜色都有一系列可能的“好处”：第一次从 x 减少到 x/2 会带来 x - x/2 的增益，下一个会带来 x/2 - x/4 的增益，依此类推。 每种颜色贡献的增益依次递减。 问题变成选择具有最大增益的操作，直到总和最多降至 S。这自然是对所有潜在减少的贪婪选择，可以使用最大堆有效管理。 

我们通过计算总和并为每种颜色推送执行第一次减少的好处来进行初始化。 每次应用操作时，我们都会弹出最佳可用增益，从总数中减去它，然后推送相同颜色的下一个增益。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(N² log A) | O(N² log A) | O(N) | 太慢了 |
 | 贪婪最大堆 | O(N log A + K log N) | O(N log A + K log N) | O(N) | 已接受 |

 ## 算法演练

 我们将问题转化为重复应用最有利可图的减少，直到满足总和约束。 

1. 计算所有气球计数的初始总和。 这代表了我们必须减少的起点。 
2. 如果总和已经小于或等于S，我们可以立即停止零操作，因为不需要归约。 
3. 对于每个颜色值 x，计算一次减少的效果：x 变为 x // 2，因此增益为 x - x // 2. 将此增益与应用一次操作后的更新值一起存储在最大优先级结构中。 
4. 提取下一次减少产生最大增益的颜色。 应用该减少，从总和中减去增益，并计算所花费的一秒时间。 
5. 对颜色应用缩减后，使用新值计算该相同颜色的下一个可能的增益。 这代表下次我们可以再次减少相同的颜色，并且必须将其重新插入结构中。 
6. 重复该过程，直到总和小于或等于 S。 

这样做的原因是每个操作独立地贡献一个明确定义的减少量，并且每种颜色的每次未来减少都是作为递减序列的一部分提前知道的。 通过始终选择当前最大的边际减少量，我们确保每一秒都用于最大化总和的立即减少，并且在仍然存在较大的减少量时不会选择更小的减少量。 

关键的不变性是，在每一步中，优先级队列都包含给定当前状态的每种颜色的下一个可用减少。 这确保了正确表示每个可能的未来动作，并且算法永远不会跳过更好的立即减少。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, S = map(int, input().split())
    a = list(map(int, input().split()))

    total = sum(a)
    if total <= S:
        print(0)
        return

    # max heap via negative values
    pq = []

    for x in a:
        if x > 0:
            gain = x - x // 2
            heapq.heappush(pq, (-gain, x))

    ops = 0

    while total > S:
        gain, x = heapq.heappop(pq)
        gain = -gain

        total -= gain
        ops += 1

        new_x = x // 2
        if new_x > 0:
            new_gain = new_x - new_x // 2
            heapq.heappush(pq, (-new_gain, new_x))

    print(ops)

if __name__ == "__main__":
    solve()
```该解决方案维护可能减少的优先级队列。 每个元素都存储颜色的当前值以及减少颜色一次的好处。 每次操作后，该颜色都会更新并重新插入其下一个潜在增益。 一旦累计减少量使总数低于所需限制，循环就会停止。 

一个微妙的细节是我们总是根据当前值计算增益，而不是根据原始值。 这是至关重要的，因为每次减半后减少顺序都会发生变化，如果不更新它就会高估未来的收益。 

## 工作示例

 考虑输入：```
2 5
3 5
```初始总数为 8，因此我们需要至少减少 3。 

| 步骤| 选择增益| 状态 (a) | 总计 |
 | --- | --- | --- | --- |
 | 0 | - | [3, 5] | 8 |
 | 1 | 2（5→2）| [3, 2] | 6 |
 | 2 | 1 (3→1) | 1 (3→1) | [1, 2] | 5 |

 两次操作后总数变为 5，满足约束条件。 

现在考虑：```
5 0
1 1 1 1 1
```初始总数为 5，目标为 0，因此必须全部消除。 

| 步骤| 选择增益| 状态 (a) | 总计 |
 | --- | --- | --- | --- |
 | 0 | - | [1,1,1,1,1] | 5 |
 | 1 | 1 | [0,1,1,1,1] | 4 |
 | 2 | 1 | [0,0,1,1,1] | 3 |
 | 3 | 1 | [0,0,0,1,1] | 2 |
 | 4 | 1 | [0,0,0,0,1] | 1 |
 | 5 | 1 | [0,0,0,0,0] | 0 |

 每个操作恰好删除一个单位，符合直觉，因为将 1 减半得到 0。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N log A + K log N) | O(N log A + K log N) | 每种颜色都会产生 O(log A) 减少量，每次从堆中推送/弹出 |
 | 空间| O(N) | 堆中每种颜色最多存储一个活动状态 |

 这些约束允许最多 1e5 种颜色和最多 1e9 种值，因此 log A 约为 30。这使堆操作总数易于管理，完全在 Python 中 1 秒执行的典型限制内。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return sys.stdout.getvalue().strip() if False else solve_capture(inp)

def solve_capture(inp: str) -> str:
    import heapq
    input = iter(inp.strip().split()).__next__

    n = int(input())
    S = int(input())
    a = [int(input()) for _ in range(n)]

    total = sum(a)
    if total <= S:
        return "0"

    pq = []
    for x in a:
        gain = x - x // 2
        pq.append((-gain, x))
    heapq.heapify(pq)

    ops = 0

    while total > S:
        gain, x = heapq.heappop(pq)
        gain = -gain
        total -= gain
        ops += 1
        nx = x // 2
        if nx > 0:
            ng = nx - nx // 2
            heapq.heappush(pq, (-ng, nx))

    return str(ops)

 ## 边缘情况

 对于 S = 0 并且所有值均为 1，算法会重复为每个元素选择增益 1，直到所有元素都变为零。 每一步正确地将总计减少一，并且堆循环遍历元素直到耗尽。 

对于已经满足的输入（例如 Total ≤ S），提前退出可以防止不必要的堆构建或操作，并立即返回零。 

对于较大的倾斜输入，例如一个巨大的值和许多较小的值，堆确保始终首先处理较大的值，因为它的初始增益占主导地位，并且随着它的缩小，其优先级自然会降低，从而允许较小的值在适当的时候接管。
