 ## 解决方案
 ## 问题理解

 该问题描述了 Phoenix 有偶数个硬币。 硬币的重量是 2 的幂，从$2^1$最多$2^n$。 他必须将所有硬币分成硬币数量相同的两组，目标是使两组总重量之间的差异尽可能小。 

输入包含几个独立的案例。 对于每种情况，值$n$告诉我们存在多少硬币。 输出是两组总和之间的最小可能绝对差。 

约束足够小，预期的解决方案不需要高级数据结构。 最大可能$n$为 30，测试用例的数量最多为 100。这意味着每个测试用例执行少量工作的解决方案很容易足够快。 然而，全面搜索所有选择方式$n/2$硬币仍然会被浪费，因为可能的分区数量呈指数增长。 为了$n=30$，选择的数量大致为$\binom{30}{15}$，这是数以亿计的可能性。 

主要的挑战是认识到两个人的权力如何表现。 最大的权重支配所有较小权重的组合，因此看起来随机的划分是没有用的。 布置时必须小心地放置最大的硬币。 

一个常见的错误是试图将最大的一半硬币放在一组中，而最小的一半放在另一组中。 例如，当$n=4$，权重是$2,4,8,16$。 这种分裂给了群体$16+8$和$2+4$，产生 18 的差异。正确答案是 6，因为最佳分割是$16+2$和$8+4$。 最大的硬币不应简单地与其他大硬币归为一组。 

另一个边缘情况出现时$n=2$。 唯一可能的分裂是$2$和$4$，所以答案是 2。如果假设两组可以完美平衡，则基于较大情况的公式的解决方案可能会意外地产生零。 

## 方法

 蛮力的想法是尝试每一种可能的选择$n/2$第一堆硬币。 对于每个选择，我们计算其权重，从总权重中减去它，并更新最小差异。 这是正确的，因为每个有效的分割都会被考虑。 问题是可能性的数量变得太多。 和$n=30$，尝试所有选择意味着四处检查$\binom{30}{15}$子集，在对每个案例进行算术之前，大约有 1.55 亿个案例。 

关键的观察来自于二的幂的结构。 最大的硬币，$2^n$，比许多较小硬币的总和要大得多。 为了保持硬币堆紧密相连，最大的硬币应与几枚最小的硬币放在一起。 剩下的大硬币应该形成另一堆。 

最佳结构是将最大的硬币和最小的硬币放在一起$n/2-1$硬币。 另一堆包含中间的$n/2$硬币。 这使得两堆硬币的数量相同，并使差异最小化，因为最大的贡献被最小的可能权重部分抵消。 

可以直接计算差异。 让第一堆包含$2^n$和最小的$n/2-1$权力。 第二堆包含从中间到$2^{n-1}$。 无需在实现中显式构建组，因为可以在迭代权力时维护总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最佳| 每个测试用例 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从最小的硬币重量开始，即$2$，并生成两个最多的幂$2^n$。 我们需要实际值，因为差异取决于权重之和。 
2. 添加最大的硬币和最小的硬币$n/2-1$硬币到第一堆。 最大的硬币会造成最大的不平衡，因此将其与最便宜的可用硬币配对是减少差异的最佳机会。 
3.添加剩余的$n/2$硬币到第二堆。 现在这两堆硬币都包含了所需数量的硬币。 
4. 计算两堆总和之间的绝对差并输出。 

为什么有效：两个硬币的威力增长得如此之快，以至于最大的硬币是在一堆硬币之间进行比较的决定因素。 如果我们把大硬币放在一起，差异就会由它们决定。 补偿最大硬币的唯一方法是将其与尽可能小的硬币配对。 所选择的结构为最大的桩提供了尽可能小的附加重量，因此没有其他有效的分割可以具有更小的差异。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())

        total_left = 0
        total_right = 0

        powers = []
        cur = 2
        for _ in range(n):
            powers.append(cur)
            cur *= 2

        for i in range(n // 2 - 1):
            total_left += powers[i]

        total_left += powers[-1]

        for i in range(n // 2 - 1, n - 1):
            total_right += powers[i]

        ans.append(str(abs(total_left - total_right)))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```该代码首先创建硬币重量的序列。 自从$n$最多为 30，将幂存储在列表中很简单，并且可以避免重复求幂。 

第一个循环构建最佳第一堆的较小支撑部分。 索引范围停止于$n/2-2$，准确给出$n/2-1$小硬币。 然后将最大的硬币单独添加。 

第二个循环从中间的硬币开始，直到最大的硬币之前的硬币。 这形成了第二堆。 边界很容易弄错，尤其是对于$n=2$，其中第一个循环必须运行零次。 使用$n//2-1$自然会处理这种情况。 

Python 整数可以在这里存储最大可能的权重，无需担心，因为$2^{30}$仍然远低于正常的整数限制。

 ## 边缘情况

 对于$n=2$，输入为：```
1
2
```生成的权重是$2$和$4$。 第一堆收到最大的硬币，而第二堆收到剩余的硬币。 区别在于$4-2=2$。 假设第一堆总是有额外的小硬币的方法在这里会失败，因为没有。 

为了$n=4$，输入为：```
1
4
```权重是$2,4,8,16$。 该算法创建第一堆为$2+16=18$第二个为$4+8=12$。 差别是 6。将所有大硬币放在一起会得到更糟糕的结果，这说明了为什么最大的硬币必须与小硬币配对。 

对于更大的情况：```
1
6
```权重是$2,4,8,16,32,64$。 第一堆变成$2+4+64=70$，第二堆就变成了$8+16+32=56$。 The difference is 14. The construction still follows the same invariant: the pile containing the largest weight has the minimum possible additional weight.
