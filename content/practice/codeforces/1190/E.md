 ## 解决方案
 ## 问题理解

 我们正在一个平面上工作，其中原点代表爆炸点。 一组人被放置在整数坐标处，我们可以画出$m$无限直线。 每个人都必须受到“保护”，因为从原点到该人的每一段都必须与至少一条选定的线相交。 从几何角度来看，这意味着从原点到集合中任何点的每条射线都必须被至少一条线切割。 

每条线路还具有一个成本，该成本是根据其距离原点的距离来衡量的。 由于所有直线都是无限的，因此距离的相关概念是从原点到直线的垂直距离。 我们希望最大化所有选定线之间的最小距离，同时仍然能够阻挡到达这些点的所有光线。 

约束条件很大：最多$10^5$点和$10^5$线。 任何独立推理每对点和线的解决方案都太慢了。 问题的结构表明，答案取决于全局几何形状，特别是原点周围的角度覆盖范围，而不是单个坐标。 

当点与原点重合时，会出现微妙的边缘情况。 在这种情况下，每条线都穿过它，因此有限的距离没有帮助。 如果至少有一个这样的点，则无论结果如何，答案都为零$m$。 

当所有点都位于非常窄的角扇区时，就会出现另一种极端情况。 在这种情况下，即使是一条精心放置的线也足够了，并且增加$m$不会增加可达到的距离，因为限制因素是几何间隔，而不是线路数量。 

第三个重要的情况是当点在角度上均匀分布时。 在这里，瓶颈变成了将圆划分为$m+1$角间隙，由最大不可避免的角间隙确定解。 

## 方法

 关键的困难在于，每条线将平面分成两个半平面，并且每个点必须位于至少一条这样的线与原点“阻挡”的区域中。 这相当于说，对于从原点开始的每个方向，在到达无穷远之前必须存在至少一条与该方向相交的线。 

蛮力方法会尝试猜测所有物体的位置和方向$m$线并验证所有光线的覆盖范围。 即使离散角度也会导致检查大量配置。 如果我们考虑$k$候选角度并尝试选择$m$线，状态空间组合增长，并且检查可行性已经成本$O(nm)$，对于$10^5$。 

关键的见解是从考虑平面上的直线转变为考虑单位圆上的角度。 每个点对应于从原点开始的一个方向。 通过原点的线定向“阻挡”连续的角度间隔。 当我们将一条线移离原点时，它在阻挡方向上的有效性取决于它的距离，并且最大化该距离对应于最小化我们需要打包这些角度约束的紧密程度。 

这将问题转化为圆上的几何填充问题：我们希望使用最多覆盖所有点方向$m$分隔符，最近线的距离由我们被迫不覆盖的最差角度间隙决定。 

核心归约是最优值由按角度顺序排序的连续点之间的最大空角度扇区控制。 一旦我们知道了间隙，我们就可以确定需要多少条线来切割它，并使用弦距离和到原点的垂直距离之间的简单几何关系从中导出最大可能距离。 

我们二分查找答案$R$，将其解释为任何线距原点的最小允许距离。 对于固定的$R$，每条线只能覆盖其方向位于由切线结构确定的特定角跨度内的点：距离处的线$R$可以阻挡宽度方向成正比的圆锥体$2\arcsin(R / r)$在哪里$r$是径向距离尺度。 这将可行性变成了检查我们是否可以贪婪地覆盖圆角数组最多$m$弧线。 

单调性至关重要：如果给定$R$有效，任何更小的$R$也有效，因为更接近原点的线在相交光线时更强大。 这允许二分搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数为$m$和离散化尺寸| 高| 太慢了 |
 | Angular 贪心 + 二分查找 |$O(n \log n \log V)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 将每个点转换为极坐标并计算其角度。 原点处的点将立即通过返回零进行处理，因为它们会使任何正距离无效。 
2. 对所有角度进行排序，并通过将每个角度加上来扩展数组$2\pi$。 这种线性化允许将圆形环绕视为一条线上的间隔覆盖。 
3.二分查找答案$R$介于零和足够大的上限之间，通常基于最大坐标幅度。 此步骤的目的是测试固定障碍距离的可行性。 
4. 对于候选人$R$，计算距离处单线的最大角跨度$R$可以有效分离。 这来自这样的几何条件：一条距离较远的线$R$从原点出发的射线相交，其方向落在可计算的角度窗口内。 
5. 对排序后的角度进行贪婪扫描。 从第一个未覆盖的方向开始，放置一条线，覆盖下式允许的最大可能角度间隔$R$。 继续，直到覆盖所有点。 
6. 计算使用了多少行。 如果超过$m$, 候选人$R$是不可行的； 否则是可行的。 
7.相应缩小二分查找范围并输出最大可行值$R$。 

关键的不变量是，在贪婪扫描期间，在每一步中，我们总是选择在角度空间中尽可能远地扩展覆盖范围的线。 这是最佳的，因为任何稍后开始的线都无法覆盖之前未覆盖的角度，并且任何覆盖较小角度范围的线都会严格增加所需的线数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import math

def can(R, angles, m):
    n = len(angles) // 2
    best = 0
    cnt = 0
    i = 0

    while i < n:
        cnt += 1
        if cnt > m:
            return False

        start = angles[i]
        j = i

        while j < i + n:
            diff = angles[j] - start
            if diff > 2 * math.acos(min(1.0, R)):
                break
            j += 1

        i = j

    return True

def solve():
    n, m = map(int, input().split())
    pts = []
    for _ in range(n):
        x, y = map(int, input().split())
        if x == 0 and y == 0:
            print(0.0)
            return
        pts.append(math.atan2(y, x))

    pts.sort()
    angles = pts + [a + 2 * math.pi for a in pts]

    lo, hi = 0.0, 1.0

    for _ in range(60):
        mid = (lo + hi) / 2
        if can(mid, angles, m):
            lo = mid
        else:
            hi = mid

    print(lo)

if __name__ == "__main__":
    solve()
```解决方案首先使用将坐标转换为角度表示`atan2`，它保留了包括象限在内的完整方向信息。 对数组进行排序和加倍可以干净地处理循环环绕，以便任何有效的覆盖间隔都成为线性数组中的连续段。 

可行性检查实施于`can`。 它贪婪地放置线：每条线覆盖当前半径约束允许的最大可能角度间隔。 表达式涉及`acos`编码距原点的距离和角度阻挡能力之间的几何关系。 

二分搜索细化最大可行半径。 大约 60 次迭代的循环计数足以保证双精度稳定性。

 ## 边缘情况

 当一个点恰好位于原点时，每条线都会相交，并且正确答案被迫为零。 该算法在任何角度计算之前都会检查这一点，以防止无效的几何推理。 

当所有点都位于非常窄的角锥内时，贪婪扫描使用很少的线，而不管$m$。 二分查找收敛到一个大的$R$，但可行性仍然正确，因为不需要额外的分区。 

当点均匀分布在圆周围时，限制因素变成角间距而不是线数。 该算法反复将圆分割成相等的可行弧，贪婪放置总是与最大的未覆盖间隙对齐，匹配最佳结构。
