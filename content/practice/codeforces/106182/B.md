 ## 解决方案
 ## 问题理解

 问题给出了一系列卡片。 每张卡有两个值，`a`和`b`。 我们必须准确选择`k`卡片并最大化所有选择的总和的乘积`a`值和所有选择的总和`b`价值观。 该牌组具有特殊的平衡属性：对于每张牌，其两个值中至少有一个最多为 100。 

输入包含多个测试用例。 对于每种情况，我们知道牌的数量以及必须打出的牌数量，然后是每张牌的两个值。 输出是所有有效选择中可能的最佳分数`k`牌。 

限制是关键。 所有测试用例的卡片总数最多为`100000`， 和`k`至多是`5`。 正常的子集搜索会大致尝试`n^k`的可能性，即使对于较小的值也是不可能的`k`什么时候`n`达到`100000`。 解决方案必须接近线性或使用卡限制中隐藏的小值。 

一个常见的错误是仅按卡片的一侧进行排序。 例如，如果我们选择最大的五张牌`a`价值观，我们可能会摧毁`b`和。 考虑：```
1
3 2
1000 1
999 100
1 100
```贪心选择由`a`给出前两张带有分数的卡片`(1999) * (101) = 201899`。 更好的选择是最后两张有分数的牌`(1000) * (200) = 200000`，所以这个例子并没有破坏它。 但是，如果我们将最后一张卡更改为`(500, 100)`，最佳集再次发生变化。 关键是，独立地最大化一侧并不代表目标，因为两个总和是相互作用的。 

另一种边缘情况是每张卡的较小一侧都很小。 例如：```
1
4 2
1000000000 1
2 1000000000
100 100
100 100
```通过平衡两个和即可得到答案。 仅跟踪大值的方法可能会忽略小贡献使产品变得更大的可能性。 

## 方法

 蛮力方法直接尝试每一个可能的组`k`牌。 对于每组，我们计算两个总和并更新答案。 这是正确的，因为每一手有效牌都经过检查。 问题是组的数量。 和`n`卡片和`k`附近`5`，选择的数量约为`n^5`，这远远超出了正常比赛的时间限制。 

有用的观察来自于平衡条件。 对于每张卡，定义`small = min(a, b)`和`large = max(a, b)`。 所选卡牌有：```
sum(a) * sum(b)
```这正是：```
(sum of small values) * (sum of large values)
```因为交换卡片上的两个值不会改变相乘的两个总数。 

所有选择的小值的总和永远不能超过`5 * 100 = 500`。 这意味着我们可以在这个小维度上使用动态规划。 在扫描卡片时，我们保留每张所选卡片的最大可能的大金额和每个可能的小金额。 

当我们处理一张卡片时，我们可以跳过它，也可以拿走它。 如果我们拿走，选择的牌张数会增加一张，小额金额会增加`small`，存储的大和增加`large`。 处理完所有内容后，答案就是最大值`small_sum * large_sum`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^k) | O(n^k) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n * k * 500) | O(k * 500) | 已接受 |

 ## 算法演练

 1. 对于每张牌，计算其较小的值和较大的值。 我们只关心 DP 状态的较小值，因为它们的总范围是有限的。 
2. 创建一个动态规划表，其中`dp[j][s]`存储通过精确选择可以获得的大值的最大总和`j`卡片的小值加起来为`s`。 
3. 初始化`dp[0][0] = 0`，这意味着不选择任何牌都会得到很大的零。 
4. 一张一张地处理每张卡片。 对于当前卡，尝试将其添加到已选择少于的每个状态`k`牌。 新状态将选择的计数和小金额增加当前卡的值。 
5. 处理完所有卡片后，检查每一个可能的小金额的状态。`k`卡片被选择了。 将小和乘以存储的大和并保留最大值。 

为什么它有效：

 每手选定的手牌都有一组固定的较小值和较大值。 DP 枚举所选牌的所有可能计数以及所有可能的较小值总和。 对于每种这样的情况，它都会保留最好的可能的较大值总和，因为较大的总和只能改善最终产品。 由于每种可能的手牌都映射到一个 DP 状态，并且每个状态都存储最佳延续，因此最终的最大值是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    INF = -10**30

    for _ in range(t):
        n, k = map(int, input().split())

        cards = []
        for _ in range(n):
            a, b = map(int, input().split())
            if a <= b:
                cards.append((a, b))
            else:
                cards.append((b, a))

        dp = [[INF] * 501 for _ in range(k + 1)]
        dp[0][0] = 0

        for small, large in cards:
            for cnt in range(k - 1, -1, -1):
                for sm in range(501 - small):
                    if dp[cnt][sm] != INF:
                        dp[cnt + 1][sm + small] = max(
                            dp[cnt + 1][sm + small],
                            dp[cnt][sm] + large
                        )

        ans = 0
        for sm in range(501):
            if dp[k][sm] != INF:
                ans = max(ans, sm * dp[k][sm])

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```输入通常被读取`sys.stdin.readline`因为卡牌总数可以达到`100000`。 DP表仅使用`k + 1`行，因为转换总是从较小的选定计数移动到较大的计数。 

循环结束`cnt`倒退。 这可以防止当前卡在同一迭代中被多次使用。 如果我们向前循环，新更新的状态可能会立即再次消耗同一张卡。 

小总和维度固定为`500`因为最多选择五张牌贡献最多`100`每个到较小的一侧。 最终的乘法在 Python 中是安全的，因为整数具有任意精度。

 ## 边缘情况

 当`k = 1`，DP 仍然有效，因为只考虑拥有一张选定卡的州。 对于输入：```
1
1 1
7 9
```较小的总和是`7`较大的总和是`9`, 给予`63`。 

当所有卡具有相同的值时，许多不同的选择都会达到相同的 DP 状态。 该州的最大金额才是最重要的，只保留最好的价值是安全的。 

对于一侧极大而另一侧很小的牌，大侧的贪婪选择会失败。 DP 将小额贡献保留为状态的一部分，因此它可以比较具有相似小金额但截然不同的大金额的组合。
