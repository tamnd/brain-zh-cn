 ## 解决方案
 ## 问题理解

 该问题模拟了运动员的国家排名系统，其中每个运动员的评级根据比赛结果和过去的表现随着时间的推移而变化。 每个运动员从一个基本评分开始，然后按时间顺序进行多项比赛。 每场比赛都有一天、一组参赛者以及每个参赛者的完成时间，零意味着取消资格。 

关键的困难在于比赛并不直接使用当前的等级。 相反，它使用比赛日前 15 天的每位运动员的评分。 根据比赛结果和那些延迟的评分，从最好的完成者的子集中计算出“比赛分数”，然后该比赛的每个参与者都会收到从比赛结果中得出的表现值。 此性能存储在其历史记录中，并随后影响其评级演变（尽管模型描述中抽象了确切的下游用法；任务重点是正确处理这些事件）。 

该结构意味着时间以两种独立的方式发挥着重要作用。 首先，比赛必须按日递增的顺序进行。 其次，每个评分查询都依赖于 15 天前的历史快照，因此我们必须维护一个时间感知结构，而不是每个运动员的简单跑步值。 

从此类问题的典型约束来看，运动员和比赛的数量足够大，不可能从头开始重新计算每场比赛的排名。 任何重复对每场比赛的参与者进行排序或重新计算全局排序的方法都可能会超出时间限制。 主要的计算压力来自于对参与者进行有效排名，同时反复查询历史评级。 

规则中自然会出现一些边缘情况。 比赛中可能会有不合格的参赛者和有效的参赛者混合在一起。 例如，如果所有参与者都被取消资格，则完赛者的数量为零，这迫使比赛被忽略或根据解释产生退化的排名情况； 仍然尝试对它们进行排名的幼稚实现可以除以零或选择无效的 top-k 参与者。 

另一个微妙的情况是比赛的完赛者很少。 如果只有一名或两名运动员完成比赛，选择最小数量有影响力的参与者的规则仍然需要至少三名或派生阈值，该阈值可能会超过有效完成者的数量。 盲目地采用顶部子集而不进行钳位的粗心实现将访问超出范围的元素。 

最后，延迟评级查询`day - 15`可以在早期比赛的任何记录更新出现之前进行。 简单的数组查找会将这些值视为零或未初始化的值，这会扭曲排名，除非我们明确定义默认基线。 

## 方法

 直接模拟按照字面上的问题陈述进行。 对于每场比赛，我们通过回顾 15 天来计算所有参与者的当前评分，按时间对所有有效完赛者进行排序（然后按打破平局的评分），选择最高组，计算比赛分数，并分配表现值。 这种方法是正确的，因为它准确地反映了定义。 

瓶颈是重复的排序步骤。 如果一场比赛有$k$参与者，分类成本$O(k \log k)$，并且在所有种族中，当总参与人数达到数十万或更多时，这就会变得令人望而却步。 此外，在没有结构的情况下重复访问“时间 t-15 的评分”会强制执行完整的历史扫描或存储每个运动员的完整时间序列，这也太大了。 

关键的观察结果是，我们每场比赛所需的唯一全局结构是通过两个键对参与者进行排序：完成时间和基于 15 天前评级的辅助键。 这种评级比较只需要在比赛内部进行，而不需要在全球范围内对所有运动员进行比较。 这意味着我们不需要全球动态排名结构； 我们只需要快速检索历史评级和高效的每场比赛排序。 

这减少了为每个运动员维护评分变化的时间索引序列并能够及时查询值的问题$d - 15$。 通过预先计算每个运动员的更新列表，这变成了每个查询的二分搜索。 每场比赛的排序仍然存在，但现在它是模型中不可避免的部分； 其他一切都变得足够高效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟|$O(\sum k_j \log k_j + m \cdot n)$|$O(mn)$| 太慢了 |
 | 时间索引历史记录 + 每场比赛排序 |$O(\sum k_j \log k_j + \sum \log H_i)$|$O(\sum H_i)$| 已接受 |

 ## 算法演练

 1. 为每个运动员存储他们随时间变化的评分列表。 每个条目都会记录当天以及该事件后的评分结果。 这让我们可以重建任何过去的评级，而无需重新计算所有内容。 
2. 按日升序处理比赛。 这确保了当我们进入稍后的比赛时，早期查询所需的所有历史记录都已经可用。 
3. 对于每场比赛，计算参考时间$t = d_j - 15$。 对于每个参与者，及时检索他们的评分$t$在他们的历史中使用二分搜索。 这是必要的，因为评级仅在离散事件时发生变化，而不是连续变化。 
4. 将参赛者分为完赛运动员和取消资格运动员。 完成者是那些时间非零的人。 被取消资格的运动员立即获得成绩值$-1$并且不影响排名。 
5. 按完成时间对完成者进行排序。 当两名运动员的时间相同时，使用他们当时检索到的评分来打破平局$t$，评分越高排名越靠前。 这种平局确保了确定性排序与模型一致。 
6. 计算$F_j$，完成者的数量。 由此，计算阈值$N_{infl} = \max(3, \lfloor 2F_j / 3 \rfloor)$。 如果$F_j < N_{infl}$，跳过此比赛的进一步处理。 
7. 选择顶部$N_{infl}$整理后的整理者。 计算其完成时间的加权平均值乘以历史评分，然后按指定的归一化常数进行缩放。 这将产生比赛分数。 
8. 为所有参与者分配绩效值。 完赛者获得$\lfloor \text{RaceScore} / R_{i,j} \rfloor$，而被取消资格的运动员则得到$-1$。 将此记录附加到每位运动员的历史记录中，以供将来查询。 

正确性取决于一个关键的不变量：在任何比赛日，比较中使用的每个评级都是 15 天前有效的评级，并且参与者的排序仅取决于那些冻结的历史值加上当前的比赛结果。 因为我们总是查询历史记录而不是在竞赛期间改变共享状态，所以未来事件不会影响过去的计算，并且所有排序决策都与时间定义保持一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from bisect import bisect_right

def get_rating(hist, day):
    # hist: list of (day, rating)
    # returns last rating with time <= day
    if not hist:
        return 0
    i = bisect_right(hist, (day, 10**30)) - 1
    return hist[i][1] if i >= 0 else 0

def solve():
    n, m = map(int, input().split())
    
    base = list(map(int, input().split()))
    
    hist = [[(-10**18, base[i])] for i in range(n)]
    
    for _ in range(m):
        parts = input().split()
        d = int(parts[0])
        s = int(parts[1])
        k = int(parts[2])
        
        participants = []
        
        idx = 3
        for _ in range(k):
            a = int(parts[idx]) - 1
            r = int(parts[idx + 1])
            idx += 2
            
            participants.append((a, r))
        
        t = d - 15
        
        finishers = []
        dsq = []
        
        for a, r in participants:
            if r == 0:
                dsq.append(a)
            else:
                rt = get_rating(hist[a], t)
                finishers.append((r, rt, a))
        
        Fj = len(finishers)
        Ninfl = max(3, (2 * Fj) // 3)
        
        if Fj >= Ninfl:
            finishers.sort(key=lambda x: (x[0], -x[1]))
            
            top = finishers[:Ninfl]
            
            score_sum = 0
            for r, rt, a in top:
                score_sum += r * rt
            
            if Ninfl > 0:
                RaceScore = (score_sum * 10000) // Ninfl
            else:
                RaceScore = 0
        else:
            RaceScore = None
        
        for a, r in participants:
            if r == 0 or RaceScore is None:
                val = -1
            else:
                val = RaceScore // r
            hist[a].append((d, val))
    
def main():
    solve()

if __name__ == "__main__":
    main()
```该解决方案维护每个运动员的历史列表，其中每个条目记录每次比赛后他们的评分变化情况。 辅助函数执行二分搜索以检索当天的评级$d - 15$，这是至关重要的，因为种族取决于历史价值观而不是当前价值观。 

在每场比赛中，我们都会将完成者与不合格的参与者分开。 完成者使用对完成时间和历史评分进行编码的元组键进行排序。 评级上的负号确保降序排列，同时保持 Python 默认的升序排序。 

比赛分数的计算遵循所选子集的精确聚合规则。 一旦计算完成，每个参与者都会收到一个派生值，该值附加到他们的历史记录中，确保未来的比赛看到更新的状态。 

一个微妙的实现细节是用“哨兵”条目初始化每个运动员的历史。 如果没有这个，早期的查询将需要特殊的外壳。 另一个重要的细节是，所有更新都是在处理比赛后附加的，以保持时间顺序的一致性。

 ## 边缘情况

 当一场比赛的所有参赛者都被取消资格时，完赛名单将变为空，并且$F_j = 0$。 在这种情况下，阈值$N_{infl} = \max(3, 0)$变成3，比完赛人数还多。 该算法正确地检测到这一点，因为条件$F_j \ge N_{infl}$立即失败，并且比赛不会产生基于评级的贡献。 然后每个参与者都会收到$-1$，符合没有足够完成者则不存在有效比赛分数的规则。 

当一场比赛的完赛者少于三名但至少有一个有效结果时，相同的阈值逻辑可以防止不安全的选择。 完成者列表可能已正确排序，但算法仍会跳过分数计算，因为未满足所需的最小样本量，从而避免在太小的集合上进行无效聚合。 

当查询$d - 15$发生在任何记录的更新之前，二分搜索返回空前缀。 哨兵初始化确保返回的评级默认为基本值，从而保留尚不存在历史记录的早期比赛的正确性。
