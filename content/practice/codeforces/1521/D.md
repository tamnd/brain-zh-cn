 ## 解决方案
 ## 问题理解

 我们从一棵树开始，这意味着一个连通图$n$顶点和精确地$n-1$边缘。 每一步都允许我们删除一条现有的边并在任意两个顶点之间插入一条新的边。 在此过程中允许结构断开连接，但在所有操作之后，我们最终必须得到一个树状结构，其中每个顶点的度数最多为 2。 这样的结构是简单的路径结构，通常称为竹子。 

任务是确定将初始树转换为跨越所有顶点的路径所需的最小边替换数。 由于每次操作都会删除一条边并添加一条边，因此边的数量始终保持不变$n-1$，所以最终的图仍然是一棵树。 唯一的限制是程度限制。 

约束允许最多$10^4$测试用例和总数$n$最多$2 \cdot 10^5$。 因此，任何解决方案平均每个测试用例都必须是线性的，因为大型树上的二次处理将超出限制。 这立即表明我们不能尝试模拟任意边缘重新布线或尝试显式枚举候选路径。 

当树已经是路径时，就会出现关键的边缘情况。 例如，一条链$1-2-3-4$已经满足度数约束，因此需要零操作。 任何基于局部度不平衡盲目执行重新布线的算法都会错误地引入不必要的操作。 

另一个重要的情况是以一个顶点为中心的星形。 例如，如果顶点$1$与所有其他相连，答案很大，因为我们必须逐步将中心度减少到最多两个，这需要系统地重新布线。 如果不考虑全局结构，贪婪的局部修复很容易低估所需边缘替换的数量。 

## 方法

 强力方法将尝试模拟所有有效操作序列，维护高度顶点的优先级结构并反复重新连接边以减少度。 虽然正确性不难争论，但分支因子是巨大的，因为每个操作都有$\Theta(n^2)$新边的可能选择。 即使限制对“有用”边缘的关注，仍然会留下可能性的组合爆炸，因为每个中间树配置都会影响未来的选择。 

关键的观察结果是，最终的结构始终是一条路径，因此重要的是在原始树中选择一条尽可能“接近”原始结构的生成路径，从而最大限度地减少必须替换的边数。 我们不再考虑边编辑，而是转变视角：我们希望以一致的顺序最大化原始树中已存在的最终路径的边数。 

这导致了树 DP 观点：根树并考虑在最终的竹子中，每个顶点的度数最多为 2，这意味着它的行为就像链的一部分。 我们可以将转换视为选择一组顶点不相交的链并将它们合并，其中当结构不兼容时，每次合并都会花费一次操作。 最佳策略简化为围绕中心结构以最佳方式配对分支，从而有效地最大限度地减少必须切割和重新布线的“额外分支”的数量。 

这个问题的一个众所周知的简化是，答案取决于我们在将树转换为单个路径时可以保留多少“良好”邻接关系，这可以通过在跟踪链端点的贪婪 DP 中生根和匹配子树来计算。

 ## 算法演练

 我们将树的根设在任意顶点。 对于每个节点，我们计算在不违反度数约束的情况下可以将多少个子子树合并到穿过该节点的单个链中。 

我们按后序处理节点，以便在处理父树之前已经对每个子树进行了汇总。 每个子子树要么贡献一个可以向上延伸的链，要么贡献一个必须打破的结构，具体取决于它是否已经具有可用的端点。 

在每个节点，我们收集来自子节点的所有“可用链端点”。 由于路径中的节点最多可以连接到两个邻居，因此我们必须选择最多两个这样的链继续向上，而所有其他节点必须被切断并重新连接。 

每次我们丢弃子链时，我们在概念上都会执行一个操作：我们删除连接该子树到当前节点的边，然后在其他地方重新连接它以维持最终路径的连接性。 此类被丢弃连接的数量直接影响了答案。 

处理完所有节点后，丢弃的子附件总数给出了所需操作的最少数量。 

构造阶段源自此 DP：每当没有选择子节点作为保留链的一部分时，我们会将其删除的边与将其连接到另一个链的合适端点的新边配对，确保我们始终保持单一的演化结构。 

### 为什么它有效

 不变的是，处理完一个节点后，其子树中的所有顶点都被排列成一组不相交的路径片段，并且这些片段中最多有两个片段有资格通过父节点进行扩展。 这与竹子中的度数约束完全匹配，因为最终结构中的任何顶点最多可以有两个入射边。 任何多余的片段都必须从当前附着点断开，并且每次断开都对应于一个必要的操作。 由于每个有效的最终竹子在每个链段上都会产生一个亲子附件，因此没有任何解决方案可以保留比该 DP 允许的更多的附件，从而建立了极小性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        g = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            a, b = map(int, input().split())
            g[a].append(b)
            g[b].append(a)

        parent = [0] * (n + 1)
        order = []
        stack = [1]
        parent[1] = -1

        while stack:
            v = stack.pop()
            order.append(v)
            for u in g[v]:
                if u == parent[v]:
                    continue
                parent[u] = v
                stack.append(u)

        children = [[] for _ in range(n + 1)]
        for v in range(2, n + 1):
            children[parent[v]].append(v)

        dp_keep = [0] * (n + 1)
        ans = 0

        for v in reversed(order):
            gains = []
            for u in children[v]:
                gains.append(dp_keep[u])
            gains.sort(reverse=True)

            if len(gains) <= 2:
                dp_keep[v] = sum(gains)
            else:
                dp_keep[v] = gains[0] + gains[1]
                ans += sum(gains[2:]) + (len(gains) - 2)

        print(ans)

if __name__ == "__main__":
    solve()
```代码首先构建树并将其根植于节点$1$。 迭代生成 DFS 排序以避免递归深度问题，然后显式构造子列表，以便子树处理变得自下而上。 

对于每个节点，我们收集子节点的贡献，表示每个子树可以保留多少个链连接。 对这些贡献进行排序允许我们保留两个最有用的延续，因为路径节点不能支持两个以上的活动方向。 所有剩余的贡献都被视为必要的削减，这直接增加了答案。 每个节点存储的 DP 值表示通过该节点向上可以保留多少个连接。 

最终答案会累积所有丢弃的附件，这对应于所需边缘替换的最小数量。 

## 工作示例

 考虑第一个形状像深度为二的星形的样本树。 我们计算叶子向上的贡献。 叶子的贡献为零，因为它们已经形成了平凡的链。 在中心，许多孩子争夺最多两个保留的联系。 

| 节点| 儿童捐款| 保留| 已删除 | DP值|
 | --- | --- | --- | --- | --- |
 | 中心 | 许多零| 2 | 所有其他| 0 |

 删除的次数等于子项的数量减二，符合路径结构中只能保留两个辐条的直觉。 

在第二个示例中，树已经是一条路径。 每个节点在根表示中最多有两个子节点，因此任何步骤都不会发生删除。 DP 永远不会触发过度修剪。 

这表明该算法保留了现有的路径结构，而没有引入不必要的修改，因为没有节点违反度数约束。

 ## 边缘情况

 已经是竹子的树行使不变量，即没有子集超过两个保留的分支，因此算法不执行修剪并返回零。 星形树则采用相反的极端，其中单个节点具有最大分支并强制最大程度地删除超过两个的附件，并且 DP 确保准确地将这些多余的连接计为操作。
