 ## 解决方案
 ## 问题理解

 我们得到了一个不同的正整数序列，我们想要使用数组中已经出现的一些未知的主值来确定该序列是否是快速排序中单个分区步骤的结果。 

一个值可以作为有效的主元，当我们围绕它分割数组时，它左边的每个元素要么位于“较小的一侧”，要么位于“较大的一侧”，与有效的分区一致：所有小于或等于主元的元素必须位于一侧，所有严格大于主元的元素必须位于另一侧。 我们没有被告知哪一侧对应于“小于主元”，但结构必须符合主元将数组分成两组的想法，并且两侧之间不会混合。 

任务是在给定数组的当前顺序的情况下识别可以充当此类主元的所有值。 如果没有值起作用，则该数组被认为不代表有效的分区结果。 如果有多个值有效，我们会按输入顺序列出它们，但最多只列出前 100 个。 

关键限制是数组长度最多可达一百万。 任何检查每个可能的主元候选并通过扫描整个数组来验证它的解决方案都会导致大约$O(n^2)$最坏情况下的行为，远远超出了可行的限度。 我们被迫采用线性或近线性方法，可能采用单通道和预先计算的结构。 

当数组看起来几乎被分区但在中间附近有一个小的违规时，就会出现微妙的边缘情况。 例如，考虑：

 输入：```
5
1 4 2 3 5
```如果我们尝试使用主元 2，则小于或等于 2 的元素必须正确分组，但 3 和 4 的放置会破坏任何一致的分割。 围绕主元值的简单本地检查会失败，因为正确性取决于所有元素的全局一致性，而不仅仅是邻居。 

另一个边缘情况是当数组已经排序时：

 输入：```
5
1 2 3 4 5
```如果我们只进行本地检查，每个元素都可能看起来是主元，但实际上只有特定位置满足分区边界条件。 

## 方法

 一种直接的方法是测试每个值作为潜在的枢轴。 对于候选主元，我们扫描整个数组并将元素分成小于或等于它的元素和大于它的元素，然后验证观察到的排序是否可以对应于有效的分区边界。 这在概念上是有效的，因为正确的主元会导致值的清晰分离。 然而，为每个$n$候选人导致$n$全面扫描，制作$O(n^2)$时间复杂度，这是不可能的$n = 10^6$。 

关键的观察是，有效的主元不仅仅与相对位置有关，而且与值的前缀后缀结构有关。 如果我们想象从左到右扫描数组，我们可以保持到目前为止看到的最大值。 任何潜在的枢轴放置在位置$i$如果它的行为就像将较小值与较大值分开的边界元素一样，则必须至少与其左侧的所有内容一样大。 类似地，从右到左扫描给出了后缀的最小约束。 

当一个值所在的位置同时是其前缀的最大值和后缀的最小值时，该值就是有效的主元。 这将问题转换为两个线性扫描和最终过滤步骤，将其简化为$O(n)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 前缀后缀检查 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取数组并按照输入顺序存储。 我们保持秩序，因为输出必须尊重它。 
2. 构建数组`pref_max`， 在哪里`pref_max[i]`是以索引结尾的前缀中的最大值`i`。 这捕获了所有可能阻止左侧枢轴“太小”的因素。 
3. 构建数组`suf_min`， 在哪里`suf_min[i]`是从索引开始的后缀中的最小值`i`。 这捕获了所有可能阻止枢轴在右侧“太大”的情况。 
4. 对于每个索引`i`，检查是否`pref_max[i] == suf_min[i] == a[i]`。 如果成立，则位置处的元素`i`正是左右分区之间的分隔值。 
5. 按顺序收集所有这些值。 如果超过 100 个，则仅输出前 100 个。 
6. 如果未找到任何值，则输出 0，表示不存在有效的分区解释。 

### 为什么它有效

 有效的主元必须是一个能够将给定排列中所有较小元素与所有较大元素完全分开的值。 如果一个值小于其左侧的某个值，则违反了前缀一致性； 如果它比其右侧的某个值大，则违反了后缀一致性。 前缀最大值确保其前面不会出现更大的值，后缀最小值可确保其后面不会出现更小的值。 当两者都与元素本身匹配时，它就成为唯一的边界，其中分割与快速排序的分区定义一致，使其成为有效的枢轴。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    pref_max = [0] * n
    suf_min = [0] * n

    cur = float('-inf')
    for i in range(n):
        cur = max(cur, a[i])
        pref_max[i] = cur

    cur = float('inf')
    for i in range(n - 1, -1, -1):
        cur = min(cur, a[i])
        suf_min[i] = cur

    res = []
    for i in range(n):
        if pref_max[i] == a[i] == suf_min[i]:
            res.append(a[i])
            if len(res) == 100:
                break

    print(len(res), *res)

if __name__ == "__main__":
    solve()
```该实现依赖于两次线性传递来构建前缀最大值和后缀最小值。 前缀扫描确保我们知道每个位置的最大约束，而后缀扫描提供从右侧开始的最小约束。 最终循环过滤同时满足这两个条件的元素。 输出规范要求提前停止 100 个候选。 

一个常见的错误是尝试仅比较邻居或本地段。 但这会失败，因为分区有效性取决于全局排序约束，而不是邻接性。

 ## 边缘情况

 一个重要的边缘情况是单元素数组，例如`1\n7\n`。 前缀最大值和后缀最小值都等于索引 0 处的元素本身，因此算法正确地返回该值作为有效主元。 

另一个边缘情况是严格降序数组，例如`4\n4 3 2 1\n`。 每个位置的前缀最大值始终等于第一个元素，而后缀最小值逐渐减小到当前元素。 每个索引都保持相等，因此每个元素都被接受，符合每个位置可以充当有效分割边界的解释。 

一种更微妙的情况是当只有一个元素在中间形成有效边界时，例如`3\n2 1 3\n`。 在索引 1 处，值 1 既是从此处开始的后缀的最小值，也是有效前缀最大结构的一部分，使其成为唯一一致的主元。 该算法自然地捕获了这一点，因为只有该索引同时满足这两个约束。
