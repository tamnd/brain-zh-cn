 ## 解决方案
 ## 问题理解

 我们得到了整数网格上树木位置的固定地图以及机器人产生的第二组观察结果。 机器人不会告诉我们它在哪里或它面向哪个方向，但它会报告它当前可以看到的所有树木的相对位置。 

每个传感器读数均在机器人的局部坐标系中给出。 一个轴对应于机器人面向的方向（向前），另一轴与其垂直（右）。 机器人保证与全局网格中的四个轴方向之一对齐，因此其局部坐标系始终是全局轴的 90 度旋转，可能会出现符号翻转。 

任务是确定是否存在由机器人位置和方向组成的唯一对，可以精确地生成给定的相对树坐标集。 如果不存在这样的配置，我们输出“Impossible”。 如果可以有多种配置，我们输出“Ambigitude”。 否则我们输出机器人的全局坐标。 

这些约束已经暗示了解决方案的结构。 树的数量最多可达 5000 棵，感测点的数量最多可达 1000 个，因此，任何尝试直接将每个配置与每个子集进行匹配的解决方案，如果它对每个候选者重新计算所有内容，都会太慢。 然而，我们可以承受数千万次简单的哈希查找或算术运算，这强烈表明解决方案必须将搜索空间减少到少量候选转换，然后有效地验证它们。 

一个微妙的点是传感器读数没有标记。 我们不知道哪个感测点对应于哪棵树。 这意味着我们正在处理四个旋转和平移之一下两个点集之间的刚性变换匹配问题。 

如果我们假设传感器点和树之间的单个任意配对修复了解决方案而不验证一致性，则会出现常见的失败情况。 例如，挑选一对可能会产生一个候选机器人位置，该位置意外地对齐了该对，但没有对齐结构的其余部分。 

另一个失败案例来自于忽视歧义性要求。 即使存在一种有效的对齐方式，也可能存在另一种方向或位置来解释数据，并且正确的输出必须反映这一点。 

## 方法

 一种直接的方法是尝试感测点和树之间的所有可能的分配，同时尝试所有四个方向。 对于每个方向，我们将尝试将每个传感器点与不同的树点进行匹配，并验证是否存在一致的平移。 这很快就变成了一个组合分配问题，其感测点数量大致为阶乘复杂度，远远超出了可行的极限。 

关键的观察是变换是刚性的并且完全由单个对应关系决定。 如果我们固定一个传感器点和一个树点，并且还固定一个方向，那么机器人的位置就变得唯一确定。 一旦机器人位置固定，所有其他传感器点都确定性地映射到全局坐标，我们只需要检查该坐标是否存在于树集中。 

这减少了从搜索匹配到枚举可管理数量的候选转换的问题。 对于每个方向，我们尝试将一个传感器点与一个树点配对来定义候选原点。 这最多会产生大约 4 × 5000 × 1000 个候选，但我们不需要以昂贵的方式完全处理所有对。 通过对树集进行恒定时间哈希查找，可以在传感器集上以线性时间验证每个候选者。

这是有效的，因为正确的解决方案必须在相同的变换下将每个传感器点映射到真实的树点。 当即使一个传感器点映射到不存在的树坐标时，任何不正确的候选者都会很快失败。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力匹配所有作业 | O(ns!) | O(1) | O(1) | 太慢了|
 | 修复一处对应关系 + 验证 | O(4·nt·ns) | O(4·nt·ns) | O(nt) | 已接受 |

 ## 算法演练

 我们分别考虑四种可能的方向。 每个方向定义了从机器人局部坐标到全局坐标的固定映射。 

1. 构建所有树坐标的哈希集，以便快速进行成员资格查询。 这允许恒定时间检查森林中是否存在变换的传感器点。 
2. 对于选定的方向，定义一个函数，将传感器读数转换为相对于机器人位置的全局偏移。 此函数对机器人面向方向隐含的旋转进行编码。 
3. 迭代每个树点和每个传感器点对。 对于每一对，计算候选机器人位置作为树坐标和变换后的传感器坐标之间的差。 此步骤是从单个对应关系推断翻译的地方。 
4. 对于每个候选机器人位置，通过使用相同方向将所有传感器点转换为全局坐标并检查每个结果点是否存在于树集中来验证它。 
5. 如果所有传感器点都映射到现有树，则将此候选点记录为有效解决方案。 
6. 检查所有方向和所有候选人来源后，确定结果。 如果不存在有效配置，则输出“Impossible”。 如果恰好存在，则输出其坐标。 如果存在多个，则输出“Ambigously”。 

### 为什么它有效

 有效的解决方案完全由方向和平移决定。 一旦单个传感器到树的对应关系在该转换下正确，翻译就被固定。 如果转换确实正确，它必须同时保留所有传感器读数，因此每个其他传感器点也必须落在现有的树上。 任何不正确的配对都会产生至少一个点立即失败的转换，因为刚性转换无法部分匹配两个不同的点集，除非它们全局一致。 

验证步骤强制执行全局一致性而不是局部兼容性，从而消除了错误候选者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def transform(x, y, orient):
    # returns (dx, dy) in global frame from robot-local coordinates
    # but we only need transformed sensor point relative to robot origin
    if orient == 0:   # north: forward +y, right +x
        return x, y
    if orient == 1:   # south: forward -y, right -x
        return -x, -y
    if orient == 2:   # east: forward +x, right -y
        return y, -x
    # west: forward -x, right +y
    return -y, x

def solve():
    nt, ns, rmax = map(int, input().split())
    trees = set()
    tree_list = []
    for _ in range(nt):
        x, y = map(int, input().split())
        trees.add((x, y))
        tree_list.append((x, y))

    sensors = []
    for _ in range(ns):
        sx, sy = map(int, input().split())
        sensors.append((sx, sy))

    solutions = set()

    for orient in range(4):
        # pre-transform all sensors for this orientation
        t_sensors = [transform(x, y, orient) for x, y in sensors]

        for tx, ty in tree_list:
            sx0, sy0 = t_sensors[0]
            ox = tx - sx0
            oy = ty - sy0

            ok = True
            for i in range(1, ns):
                x = ox + t_sensors[i][0]
                y = oy + t_sensors[i][1]
                if (x, y) not in trees:
                    ok = False
                    break

            if ok:
                solutions.add((ox, oy))

                if len(solutions) > 1:
                    print("Ambiguous")
                    return

    if len(solutions) == 0:
        print("Impossible")
    else:
        x, y = solutions.pop()
        print(x, y)

if __name__ == "__main__":
    solve()
```核心实现选择是预先转换每个方向的传感器坐标，以便将机器人框架简化为简单的平移问题。 完成此操作后，每个候选源都使用减法从单个传感器树配对中派生出来，并且验证变成了哈希集中的简单成员资格检查。 

一个微妙的细节是在验证过程中将一个传感器点固定为锚点。 这避免了从所有传感器树对重复重新计算候选起点。 相反，每棵树都充当第一个传感器点的潜在匹配，这足以生成所有可能的翻译。 

通过存储所有有效的机器人位置来全局跟踪模糊性。 一旦出现多个不同的位置，我们就可以提前终止。

 只有正确的锚点配对才能产生通过所有传感器检查的原点。 

现在考虑一种情况，两个不同的方向都解释相同的传感器配置。 该算法将在解集中找到两个不同的原点。 

| 方向| 找到原点 | 有效传感器覆盖范围 | 已存储|
 | ---| ---| ---| ---|

 由于存在两个不同的解决方案，因此最终输出变得“不明确”。

 ## 边缘情况

 当多个树点在不同方向下重合时，会出现一种棘手的情况，从而产生相同的候选原点。 该算法可以处理此问题，因为每个候选来源都经过全局验证，而不仅仅是本地验证。 

另一种情况是，存在正确的锚对，但其他传感器点在该转换下失败。 这在验证过程中会立即被拒绝，从而防止部分几何匹配出现误报。 

最后一种边缘情况是仅存在一个传感器点时。 在这种情况下，每个树点都会产生一个有效的候选原点，并且解决方案必须正确检测歧义，除非所有候选原点都重合，而这种情况仅在只有一个树点时才会发生。
