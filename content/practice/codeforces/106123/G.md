 ## 解决方案
 ## 问题理解

 问题描述了一行`n`杯子放置在位置`1`通过`n`。 第一个杯子下面有一根骨头。 有些位置存在漏洞。 在成对的杯子位置之间执行一系列交换。 在交换过程中，两个杯子会立即交换位置，因此只有当骨头位于交换的杯子之一内时才会移动。 如果骨头在任何交换后到达一个洞，它就会掉下来并永久消失。 任务是确定骨头的最终位置，或者报告它已经掉落。 

输入给出了杯子位置的数量、孔的数量、交换的数量、孔的位置，然后是交换操作。 输出是所有操作后包含骨骼的最终位置，除非骨骼在孔中丢失。 

这些限制使预期的解决方案变得清晰。 操作数量可能足够大，以至于无需模拟给定交换之外的任何内容。 每次交换仅影响两个位置，因此每次交换花费恒定时间的解决方案是理想的。 构建昂贵的数据结构或在每次操作后检查每个杯子会带来可避免的开销。 

棘手的情况来自这样一个事实：掉进洞里会阻止所有未来的运动。 一个常见的错误是在骨头消失后继续应用交换。 

例如，如果输入是：```
3 1 2
2
1 2
2 3
```骨骼开始于位置`1`。 第一次交换将其移动到位置`2`，那里有一个洞，所以正确的输出是：```
-1
```粗心的模拟会忽略孔，直到最后将骨骼从位置移动`2`定位`3`并打印错误答案。 

另一种边缘情况是交换不涉及当前骨骼位置。 例如：```
5 0 2
1 2
4 5
```骨头开始于`1`。 第一次交换将其移至`2`，第二次交换不影响。 答案是：```
2
```在没有正确跟踪骨骼位置的情况下交换杯子的实现可能会意外地再次移动骨骼。 

## 方法

 直接的方法是保持当前的骨骼位置并处理每次交换。 对于每个操作，如果骨骼位于两个交换位置之一，它将移动到另一个位置。 移动后，我们检查新位置是否是一个洞。 如果是的话，骨头就消失了。 

这种强力方法已经是最佳的，因为输入本身描述了唯一可以改变答案的事件。 无需重建杯子的整个排列。 唯一相关的信息是骨骼的位置以及该位置是否是孔。 

更复杂的模拟可能会存储每个杯子并在每次交换期间移动物体。 这在概念上是可行的，但它跟踪的是无关紧要的信息。 杯子只是骨头周围的标签，而问题只询问骨头。 由于交换仅在当前位置是交换位置之一时更改骨骼的位置，因此我们可以将整个过程简化为单个整数更新。 

此处的强力解决方案和最佳解决方案是相同的，因为直接模拟已经是尽可能少的工作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(k) | O(n) | 已接受 |
 | 最佳 | O(k) | O(n) | 已接受 |

 ## 算法演练

 1. 将所有孔位置存储在一组中。 集合允许我们在恒定的平均时间内检查骨骼是否在移动后掉落。 
2. 初始化骨骼位置为`1`，因为骨头从第一个杯子下方开始。 
3. 逐一处理交换。 对于职位之间的交换`u`和`v`，将骨骼从`u`到`v`或来自`v`到`u`仅当它当前位于其中一个杯子下方时。 如果两个位置都不包含骨骼，则交换对答案没有影响。 
4、每次动作结束后，检查新骨骼位置是否为孔。 如果是，则将骨骼标记为丢失并停止处理未来的交换。 
5. 如果所有交换均已处理且没有丢失骨骼，则打印其最终位置。 

为什么它有效：

 每时每刻，杯子排列中唯一重要的部分是当前隐藏骨头的杯子。 当该杯子参与交换时，交换会准确地改变骨骼的位置。 该算法精确应用这些更改并忽略不会影响骨骼的交换。 在每次可能的移动之后，它会立即检查孔的状况，以匹配流程的规则。 由于状态在每次操作后都会更新，因此最终存储的位置正是真实的结果。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    holes = set(map(int, input().split()))

    pos = 1
    alive = True

    for _ in range(k):
        u, v = map(int, input().split())

        if alive:
            if pos == u:
                pos = v
            elif pos == v:
                pos = u

            if pos in holes:
                alive = False

    print(pos if alive else -1)

if __name__ == "__main__":
    solve()
```该解决方案在哈希集中存储漏洞，因为每次交换后都会进行成员资格检查。 列表也可以，但是集合直接代表我们需要的操作：询问一个位置是否危险。 

变量`pos`是模拟的完整状态。 无需存储杯子内容物，因为交换仅在触及此位置时才有意义。 

这`alive`flag 可以防止骨头掉落后后续交换改变答案。 这符合问题规则，即骨头一旦到达孔洞就不再位于任何杯子内。 

操作顺序很重要。 交换必须在检查孔之前进行，因为骨头只有在到达新位置后才会掉落。 移动之前进行检查会漏掉交换将骨头直接放入孔中的情况。

 ## 边缘情况

 当骨头掉进洞里时，未来的交换一定不能让它复活。 在：```
3 1 2
2
1 2
2 3
```第一次交换将骨骼从`1`到`2`。 该算法立即发现`2`是一个孔并设置`alive`为假。 第二个交换被读取但无法更改答案，因此输出为`-1`。 

当交换不涉及骨骼时，位置必须保持不变。 在：```
5 0 2
1 2
4 5
```第一次交换将骨骼从`1`到`2`。 第二次交换只交换杯子`4`和`5`，所以骨骼保持在`2`。 该算法仅检查是否`pos`匹配交换的端点之一，这保留了正确的状态。 

当没有交换时，答案只是初始位置，除非该位置已经是一个洞。 该算法开始于`pos = 1`并且不执行任何更新，因此它自然可以处理这种情况。
