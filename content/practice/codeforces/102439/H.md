 ## 解决方案
 ## 问题理解

 对于整数 (x)，划掉数字意味着从其小数表示中删除一些位置，同时保留所有剩余数字的原始顺序。 如果可以通过这种方式获得正斐波那契数，则该数字不受欢迎。 我们需要统计包含范围（[0,n]）内不被不喜欢的数字。 

例如，（193）不受欢迎，因为删除它的中间数字留下（13），这是斐波那契数。 另一方面，(4) 很受欢迎，因为从它的数字中无法获得正的斐波那契数。 官方限制允许最多十个测试用例，其中（n）大到（10^{18}）。 

(10^{18}) 的上限是关键约束。 迭代每个整数是不可能的，因为一个测试用例中可能有 (10^{18}+1) 个候选者。 我们需要使用 (n) 最多 19 位十进制数字，因此基于数字的计数方法是自然的目标。 

有几种边界情况很容易破坏粗心的实现。 对于（n=0），答案是（1），因为范围内唯一的数字是（0），并且喜欢零。 仅计算正数的实现将错误地返回 (0)。 

对于(n=4)，答案是(2)，即(0)和(4)。 数字 (1,2,3) 不能出现在喜欢的正数中，因为每个数字本身都是正斐波那契数。 仅检查至少两位数的斐波那契数的解决方案会错误地计算 (1,2,3)。 

对于 (n=2019)，答案是 (125)。 四位数字的第一位最多（2019）必须是（1）或（2），并且这两个数字都被禁止。 因此，没有新的四位数喜欢的号码。 简单地计算由允许的数字组成的所有字符串而不考虑上限的解决方案可能会过度计数。 

前导零也需要仔细处理。 数字 (04) 不是与 (4) 分开的整数，因此数字内部可以使用零，但不能用作正数的第一位。 

## 方法

 直接的方法是检查从 (0) 到 (n) 的每个整数 (x)。 对于每个（x），我们可以生成直到（x）的所有斐波那契数，然后测试它们的任何十进制字符串是否是（x）的十进制表示的子序列。 由于斐波那契数呈指数级增长，因此 (10^{18}) 以下的相关斐波那契数大约只有 90 个，每个数最多有 19 位数字。 该方法是正确的，因为当至少一个斐波那契字符串作为子序列出现时，就会不喜欢某个数字。 

问题是候选整数的数量。 在最坏的情况下，我们对一个测试用例执行大约 (10^{18}\cdot90\cdot19=1.71\cdot10^{21}) 位数字比较。 即使在考虑 Python 开销之前，这也远远超出了一秒的限制。 

有用的观察来自最小的斐波那契数。 正的一位数斐波那契数是 (1,2,3,5,8)。 如果一个号码包含任何这些数字，则该单个数字本身可以保留，因此该号码会立即被讨厌。 因此，每个喜欢的号码只能包含数字

 [
 {0,4,6,7,9}。 
]

 此时我们仍然需要担心多位斐波那契数，其每一位都属于这个集合。 斐波那契数最多只有 19 位（10^{18}），并且只需要检查大约 90 个斐波那契值。 生成它们一次并检查它们的小数位表明，直到 (10^{18}) 的正斐波那契数都不完全由 (0,4,6,7,9) 组成。 因此，多位斐波那契数不能是仅使用这五位数字的数的子序列。 

这将原始问题简化为一个更简单的问题：最多计算 (n) 个十进制表示仅使用 (0,4,6,7,9) 的整数。 剩下的工作是标准的数字计数程序。

蛮力方法之所以有效，是因为它直接测试定义，但由于范围巨大而失败。 一位数斐波那契数消除了五个小数位的观察结果将复杂的子序列条件压缩为对每个数字的简单限制。 一旦剩余的斐波那契候选数耗尽，问题就变成了计算受限十进制字符串。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(n\cdot 90\cdot 19)) | (O(90)) | 太慢了|
 | 最佳 | 每个测试用例 (O(19\cdot 10)) | (O(19)) | 已接受 |

 ## 算法演练

 1. 单独对待(0)。 它是一个受欢迎的整数，因此它为每个 (n\ge0) 的答案贡献 1。 
2. 对于每个正整数，第一个位置只能是数字 (4,6,7,9)。 仅允许在第一个位置之后使用数字 (0)，因为前导零不构成十进制表示的一部分。 
3. 对于每个比 (n) 中的位数短的可能长度，计算该长度的所有有效数字。 长度为正数 (k) 的第一个数字有四种选择，后面的每个数字有五个选择，给出 (4\cdot5^{k-1}) 种可能性。 
4. 计算与(n)长度完全相同的有效数字。 从左到右处理(n)的数字。 在每个位置，计算有多少个允许的数字小于（n）的相应数字。 选择任何这样的较小数字会使整个前缀更小，因此所有剩余位置都可以用五个允许的数字独立填充。 
5. 如果(n)的当前数字不允许，则立即停止。 到目前为止构造的前缀已经可以小于(n)，并且任何保留当前禁止数字的数字都将无效。 
6. 如果允许(n) 本身的每个数字，则在末尾加1 以包含(n) 本身。 否则，任何与 (n) 具有完全相同前缀的数字都是有效的。 

### 为什么它有效

 每个不喜欢的数字必须至少包含一个正斐波那契数作为子序列。 由于 (1,2,3,5,8) 是斐波那契数，因此喜欢的数不能包含任何这些数字。 相反，将每个数字限制为 (0,4,6,7,9) 后，直到 (10^{18}) 的正斐波那契数都不可能作为完整的数字字符串，因此也不可能作为子序列出现。 因此，喜欢的数字正是其小数位属于该允许集合的整数。 

计数过程仅检查每个可能的有效十进制表示一次。 对于较短的长度，第一个数字有四个选择，后面的每个数字有五个选择。 对于(n)的长度，每当我们在第一个不同的位置选择较小的数字时，除了允许数字条件外，其余后缀不受限制。 如果当前数字无法匹配，则等前缀分支消失。 这对最多 (n) 个有效数字进行划分，没有重叠或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

ALLOWED = "04679"
FIRST = "4679"

def count_liked(n: int) -> int:
    s = str(n)
    length = len(s)

    # The number 0 is always liked.
    ans = 1

    # Count all positive valid numbers with fewer digits.
    power = 1
    for digits in range(1, length):
        ans += 4 * power
        power *= 5

    # Count valid numbers with exactly len(s) digits and <= n.
    for i, ch in enumerate(s):
        d = ord(ch) - ord('0')

        choices = FIRST if i == 0 else ALLOWED

        smaller = 0
        for c in choices:
            if ord(c) - ord('0') < d:
                smaller += 1

        # Once this position is made smaller than n,
        # every remaining position can be filled freely.
        remaining = length - i - 1
        ans += smaller * (5 ** remaining)

        # We cannot continue with the same prefix.
        if ch not in choices:
            return ans

    # n itself uses only allowed digits.
    return ans + 1

def solve() -> None:
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        out.append(str(count_liked(n)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```这`ALLOWED`字符串表示第一个位置之后可能出现的所有数字。 它包含零，因为内部零是有效的，而`FIRST`排除零以防止出现前导零。 

初始值`ans = 1`占零。 即使当 (n=0) 时，这也是必要的，因为该范围是包含在内的。 

第一个循环处理每个较短的正长度。 变量`power`从 (5^0) 开始，因此一位数字的贡献是 (4)，然后是 (20)，然后是 (100)，依此类推。 每个长度之后都乘以五。 

第二个循环实现了算法中的紧前缀计数。 假设(n)的当前数字是(6)。 在非前导位置，允许的较小数字是（0）和（4），因此有两个可能的较小分支。 一旦选择其中之一，所有剩余位置各有五个选择，给出 (2\cdot5^{\text{剩余}}) 个数字。 

当当前数字被禁止时提前返回可以干净地处理上限条件。 我们计算在当前位置首先变小的每个有效数字，但我们不能继续沿着精确的前缀，因为这需要使用禁止的数字。 

如果每个数字都幸存下来，则 (n) 本身就是有效数字并且必须包含在内。 决赛`+ 1`正是处理这种情况。 

Python 整数具有任意精度，因此 (5^{18}) 等值不会溢出。 与 Python 整数所能表示的相比，最大相关幂很小。

 ## 边缘情况

 对于 (n=0)，算法开始于`ans = 1`并且没有正长度可供计算。 数字`0`仅在内部允许，但在这里它表示整数零本身，这是明确喜欢的。 因此结果是（1）。 

对于 (n=1)，初始零贡献 1。 第一个数字是`1`，这不在`FIRST`，因此最多没有有效的正一位数 (1)。 该函数返回 (1)，这是正确的。 

对于（n=4），允许第一位数字，但不允许小于小于的正数`4`。 然后该算法将 (4) 本身相加，得到 (0,4)，从而得到 (2)。 

对于(n=9)，所有四个允许的正一位数(4,6,7,9)至多为(9)。 该算法计算较小的选择`4`,`6`， 和`7`，然后添加`9`本身，最后包括零。 结果是(5)。 

对于 (n=10)，一位数计数仍为 (5)。 最多不存在有效的两位数 (10)，因为每个正的两位数有效数都以 (4)、(6)、(7) 或 (9) 开头。 第一个数字`1`被禁止，因此紧密分支停止，答案仍然是 (5)。 

对于 (n=2019)，相同的逻辑适用于第一个位置。 数字`2`被禁止，并且每个有效的四位数字至少以`4`，因此 (2019) 以下不能容纳任何四位有效数字。 三个较短的正长度贡献 (4+20+100=124)，零贡献一，产生 (125)。 

对于(n=10^{18})，输入有19位数字，但它的第一个数字是`1`，这是禁止的。 每个有效的 19 位数字都以`4`,`6`,`7`， 或者`9`，所以最多没有一个是 (10^{18})。 所有有效数字最多为 18 位，包括零在内的数字为 (5^{18}=3814697265625)。 该实现可以在不溢出的情况下处理此问题，因为 Python 整数是任意精度的。
