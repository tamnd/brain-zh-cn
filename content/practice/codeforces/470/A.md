 ## 解决方案
 ## 问题理解

 该问题中的序列来自于对六边形网格上不断增长的六边形内的格点进行计数。 该问题已经给出了序列的公式，而不必手动构造六边形或计数点：$$H_n = 3 \cdot n \cdot (n+1) + 1$$输入由单个整数组成`n`，表示我们需要计算的序列元素的索引。 输出的值为$H_n$。 

限制非常小。 的价值`n`介于 0 和 9 之间（含 0 和 9）。 即使是最大的可能答案也很小：$$H_9 = 3 \cdot 9 \cdot 10 + 1 = 271$$由于这些限制，性能不再是问题。 任何合理的解决方案都会立即运行。 真正的任务只是正确应用给定的公式。 

一种边缘情况是`n = 0`。 许多序列问题从索引 1 开始，粗心的实现可能会意外地假设这一点。 例如：

 输入：```
0
```正确输出：```
1
```代入公式可得：$$3 \cdot 0 \cdot 1 + 1 = 1$$另一个常见的错误是将公式误读为`3*n*n + 1`而不是`3*n*(n+1) + 1`。 

例如：

 输入：```
1
```正确输出：```
7
```正确的计算是：$$3 \cdot 1 \cdot 2 + 1 = 7$$使用`3*n*n+1`会错误地产生 4。 

## 方法

 强力解释是对六边形晶格进行实际建模，并计算六边形中包含的所有点：`n+1`每一侧的点。 这样的解决方案将生成坐标，确定哪些点属于该形状，并对它们进行计数。 这是正确的，因为它直接模拟了序列的几何定义。 

尽管限制很小，但这种方法是不必要的。 该问题已经提供了答案的精确公式。 一旦序列定义以代数方式给出，就没有理由重建几何结构。 

关键的观察结果是期望值明确定义为：$$H_n = 3n(n+1)+1$$所以整个问题归结为阅读`n`，计算表达式并打印结果。

 ## 算法演练

 1.读取整数`n`从输入。 
2. 使用给定公式计算序列值：$$H_n = 3 \cdot n \cdot (n+1) + 1$$这正是序列的定义方式，因此不需要额外的推导。 
3. 输出计算值。 

### 为什么它有效

 该问题直接将序列元素定义为：$$H_n = 3n(n+1)+1$$该算法针对给定的输入评估该公式`n`。 由于公式本身就是序列的定义，因此计算出的值正是所需的答案。 没有任何近似、模拟或中间推理可以改变结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
print(3 * n * (n + 1) + 1)
```程序首先读取单个输入值`n`。 

然后它评估`3 * n * (n + 1) + 1`，匹配语句中给出的数学定义。 根据Python的运算符优先级，乘法在加法之前执行，但是括号周围`(n + 1)`使预期的计算完全明确。 

最后，打印结果。 

不存在边界问题，因为该公式适用于每个有效输入，包括`n = 0`。 整数溢出在Python中也是不可能的，这个问题的最大答案只有271。

## 测试用例```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline
    n = int(input())
    print(3 * n * (n + 1) + 1)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue().strip()

# provided sample
