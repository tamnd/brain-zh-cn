 ## 解决方案
 ## 问题理解

 该问题要求我们获取一个整数列表，并为每个元素生成该元素与其前一个元素的总和。 不同之处在于输出的第一个元素与数组的最后一个元素配对，从而创建循环关系。 从概念上讲，您可以将其视为形成一个数字环，其中每个数字都与其前一个数字连接，并且输出是沿环的每个链接的总和。 

数组长度，$n$，范围从 2 到 50，每个元素在 1 到 1000 之间。这是一个很小的输入大小，因此简单的线性传递就足够了，无需担心性能。 主要的微妙之处在于处理从第一个元素到最后一个元素的环绕，作为一个始终访问的简单实现$a[i-1]$开始于$i = 0$会索引越界或元素错配。 

当出现边缘情况时$n = 2$，其中第一个元素的前一个元素是第二个元素，反之亦然。 用于输入`2 5 7`，输出应该是`12 12`。 另一种情况是所有元素都相等； 为了`4 3 3 3 3`，总和是`6 6 6 6`。 粗心的实施可能会错误地改变指数并产生`3 6 6 6`。 

## 方法

 最直接的方法是蛮力：迭代数组，并对每个索引$i$，输出总和$a[i]$和$a[i-1]$。 要处理第一个元素，您需要显式地单独处理它，并将其与最后一个元素求和。 这种方法需要对数组进行一次遍历，对每个元素执行一次加法。 时间复杂度为$O(n)$，这是可以接受的$n \le 50$。 除了输出数组之外不需要任何额外的存储，因此空间复杂度为$O(n)$。 

没有根本上更快的方法，因为操作必须至少接触每个元素一次。 关键的见解是正确管理数组的循环性质，这可以通过模运算来实现：元素的前一个索引$i$是$(i - 1 + n) \% n$。 这个单一公式概括了环绕并完全消除了特殊的外壳。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 已接受 |
 | 模块化索引 | O(n) | O(n) | 已接受 |

 两种方法在性能上实际上是相同的； 区别在于代码的优雅性和避免差一错误。 

## 算法演练

 1. 读取输入并将其拆分为整数数组。 存储数组长度$n$分别地。 这确保了迭代和处理索引时的清晰度。 
2. 初始化一个空列表来存储输出总和。 这将计算与打印分开并允许轻松调试。 
3. 迭代从 0 到$n-1$。 对于每个索引$i$，将前一个索引计算为$(i-1+n) \% n$。 此公式正确地环绕第一个元素以将其与最后一个元素配对。 
4.添加当前元素$a[i]$对其前身$a[prev\_index]$并将结果附加到输出列表中。 这保持了问题所需的顺序。 
5. 完成迭代后，将总和列表连接成空格分隔的字符串并打印它。 这会产生完全预期的输出格式。 

工作原理：在每一步中，算法都保持不变性，即每个元素都与其循环意义上的前一个元素精确相加。 模运算确保第一个元素与最后一个元素正确配对。 由于每个元素都被访问一次并与正确的伙伴组合，因此该算法不会产生错误的总和或未对齐的输出。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# read input
data = list(map(int, input().split()))
n = data[0]
a = data[1:]

result = []
for i in range(n):
    prev_index = (i - 1 + n) % n
    result.append(a[i] + a[prev_index])

print(' '.join(map(str, result)))
```第一行确保快速输入。`data`两者皆有$n$和数组元素。 我们分开$n$从`a`澄清索引和长度。 该循环使用模块化索引计算总和，这避免了第一个元素的任何特殊大小写。 最后，我们将每个整数和转换为字符串，并用空格连接它们以完全匹配输出格式。 忘记模运算或未对齐索引将导致错误的输出。

 ## 边缘情况

 对于输入`2 5 7`，该算法将总和计算为`5+7=12`和`7+5=12`，正确处理循环配对。 为了`3 1 1 1`，每个总和是`1+1=2`，验证统一数组是否有效。 这些测试证实，模块化索引成功地消除了边界问题和相差一错误，即使在数组极端情况下也是如此。
