 ## 解决方案
 ## 问题理解

 一组 N 名参与者想要参观编号为 1 到 K 的旅游景点。每个参与者都有一张他们拒绝参观的地方的清单。 如果我们从 l 到 r 中选择任何连续的参与者片段，则该组只有在该片段中没有人拒绝的情况下才愿意去一个地方。 

因此，对于每个查询 [l，r]，我们有效地获取该区间内的所有参与者，收集他们中任何人不喜欢的每个位置，并从考虑中删除这些位置。 答案是从 1 到 K 的一组位置，在区间内没有任何人禁止。 

换句话说，每个人都定义了一个禁止地点的子集，并且查询要求在连续范围的人中对这些禁止的子集的并集进行补集。 

这些约束强烈地塑造了解决方案。 N 最大为 100000，Q 最大为 200000，因此任何扫描每个查询间隔的解决方案都太慢。 K 最多为 60，这个值足够小，我们有能力维护所有参与者的每个位置的统计数据。 这种不对称性，即 N 和 Q 较大，而 K 较小，是关键的结构提示。 

一个天真的想法是，对于每个查询，迭代 [l, r] 中的所有参与者，在大小为 K 的布尔数组中标记禁止位置，然后输出剩余的位置。 这将需要 O((r-l+1)·K) 每个查询，在最坏的情况下退化为 O(NKQ) 并且远远超出限制。 

当许多查询覆盖较大的间隔时，会出现更微妙的失败情况。 即使K很小，重复扫描长距离也会超时。 

## 方法

 暴力方法独立处理每个查询。 对于查询 [l, r]，我们初始化一个大小为 K 的数组，假设所有位置都是允许的，然后扫描范围内的每个参与者并标记他们的禁止位置。 最后，我们输出所有未标记的地方。 这是正确的，因为它直接模拟问题的定义，但每个查询可能需要扫描最多 N 个参与者并更新每个参与者最多 K 个标志。 当 Q 达到 200000 时，这变得太慢了。 

关键的观察是我们不需要为每个查询从头开始重新计算信息。 对于每个地方，重要的只是 [l, r] 中是否至少有一个参与者禁止它。 这将问题转换为对参与者索引的二进制数组进行按位置范围存在性查询。 

我们可以为每个位置 k 预先计算参与者的前缀和，指示索引 i 之前有多少人禁止 k。 然后，对于查询[l，r]，我们可以通过检查前缀和差是否为零，在每个位置的恒定时间内确定k是否出现在区间内的任何禁止列表中。 这将每个查询减少到 O(K)，这是可以接受的，因为 K 最多为 60。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(Q·N·K) | O(Q·N·K) | O(K) | 太慢了|
 | 每个地方的前缀总和 | O(N·K + Q·K) | O(N·K + Q·K) | O(N·K) | O(N·K) | 已接受 |

 ## 算法演练

 我们将输入重新解释为二进制矩阵，其中行对应于参与者，列对应于地点。 如果参与者 i 拒绝地点 k，则条目 (i, k) 为 1，否则为 0。 

然后，我们预处理按列的前缀和，以便我们可以快速回答范围内是否存在任何 1。

1. 建立一个表 pref[k][i] ，表示从 1 到 i 有多少参与者禁止地点 k。 我们在读取输入时逐渐填充它。 这将分散的列表转换为支持快速范围查询的结构。 
2. 对于每个参与者 i，我们迭代其禁止列表，并为这些 k 标记 pref[k][i] = pref[k][i-1] + 1，而所有其他 k 则简单地继承 pref[k][i-1]。 这确保了正确性，因为每列独立地跟踪累积发生次数。 
3. 预处理后，通过检查从 1 到 K 的每个 k 来回答每个查询 [l, r]。我们计算 pref[k][r] - pref[k][l-1]。 如果该值为零，则说明该区间内没有人禁止放置 k，因此它是有效的。 
4. 按升序收集所有有效的 k。 如果不存在，则输出-1。 

我们显式迭代每个查询的所有 k 的原因是 K 很小且固定，因此与 N 或 Q 相比，即使每个查询 60 次检查也可以忽略不计。 

### 为什么它有效

 对于每个位置 k，前缀和数组精确编码 k 出现在禁止列表中直至每个位置的次数。 当且仅当累积计数在该段内不增加时，范围 [l, r] 不包含 k 的禁止出现，这相当于 pref[k][r] = pref[k][l-1]。 由于每个位置都是独立的，因此检查所有 k 会重建完整的允许位置集，而不会丢失参与者之间的交互。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    N, K = map(int, input().split())
    
    # pref[k][i]: number of times place k is forbidden in [1..i]
    # using 1-based indexing for convenience
    pref = [[0] * (N + 1) for _ in range(K + 1)]

    for i in range(1, N + 1):
        data = list(map(int, input().split()))
        m = data[0]
        forbidden = data[1:]
        
        # carry previous prefix values
        for k in range(1, K + 1):
            pref[k][i] = pref[k][i - 1]
        
        for k in forbidden:
            pref[k][i] += 1

    Q = int(input())
    out = []

    for _ in range(Q):
        l, r = map(int, input().split())
        ans = []
        
        for k in range(1, K + 1):
            if pref[k][r] - pref[k][l - 1] == 0:
                ans.append(str(k))
        
        if not ans:
            out.append("-1")
        else:
            out.append(" ".join(ans))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```预处理步骤同时构建 K 个前缀数组。 关键的实现细节是在对当前参与者应用更新之前将 pref[k][i-1] 复制到 pref[k][i] 中。 这确保每个参与者仅增加他们明确禁止的地点的计数，而所有其他地点保持不变。 

查询步骤完全依赖于前缀差异，因此不需要对参与者进行每次查询扫描。 

## 工作示例

 考虑一个有 3 个参与者和 5 个地点的小场景。 

参与者 1 禁止 2。 

参与者 2 禁止 2 和 5。 

参与者 3 没有禁止任何事情。 

查询 [1, 2] 询问参与者 1 和 2 都允许的位置。 

我们构建前缀计数：

 | 我| 福布(2) | 福布(5) |
 | --- | --- | --- |
 | 1 | 1 | 0 |
 | 2 | 2 | 1 |
 | 3 | 2 | 1 |

 对于查询 [1,2]，位置 2 的计数为 2 - 0 = 2，因此被排除。 第 5 处有 1 - 0 = 1，也被排除。 位置 1、3、4 仍然有效，因此输出为 1 3 4。 

现在考虑查询 [2,3]。 这里参与者 3 没有添加任何限制。 

| k | 首选项[k][3] - 首选项[k][1] |
 | --- | --- |
 | 2 | 2 - 1 = 1 |
 | 5 | 1 - 0 = 1 |

 因此，再次排除 2 和 5，相同的结果结构，显示前缀差异如何正确隔离间隔。 

这表明该算法仅依赖于区间内的计数，而不依赖于区间外的绝对位置。

 ## 边缘情况

 一个微妙的情况是参与者不禁止任何地方。 在这种情况下，他们的行不应修改任何前缀计数，并且仅包含此类参与者的查询应返回所有位置。 由于没有应用增量，前缀结构自然可以处理这个问题。 

另一种情况是查询涵盖单个参与者。 答案应该只是该参与者的禁止集的补充。 前缀差异精确地减少为检查一行，因为 pref[k][r] - pref[k][l-1] 隔离单个索引。 

最后，当K=1时，输出要么是“1”，要么是“-1”。 该算法仍然有效，因为 k 上的循环退化为每个查询一次检查，并且前缀和正确反映了该范围内是否曾经禁止该唯一位置。
