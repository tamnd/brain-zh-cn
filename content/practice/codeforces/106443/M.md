 ## 解决方案
 ## 问题理解

 我们给出了索引从 0 到 m − 1 的建筑物的圆形排列。仅允许移动到圆上的相邻建筑物，因此从位置 i 可以移动到 i + 1 modulo m 或 i − 1 modulo m，两个位置之间的距离是沿圆移动的最短次数。 

一组 n 人，每人从某个建筑物 a[i] 开始。 我们可以选择一栋 h 楼作为集合地点。 每个人都走最短的环形路径走到h。 选择 h 的成本是从每个 a[i] 到 h 的所有单独最短距离的总和。 任务是在 h 的所有可能选择中找到最小可能成本。 

关键结构是我们正在优化到单个点的圆形距离之和。 这是一个经典的“选择循环中的最佳根”问题，其中对每个候选者的简单评估有效，但需要改进。 

约束 n, m ≤ 2 × 10^5 意味着任何尝试所有 h 并从头开始重新计算距离的解决方案都需要 O(nm)，这太慢了。 甚至 O(m log m) 或 O(m √m) 方法也是不必要的； 我们的目标应该是 O(n + m) 或 O(n log n)。 

一个微妙的问题是距离是圆形的，而不是线性的。 直接处理 0 到 m − 1 行而不考虑回绕的天真的尝试将会失败。 例如，在 0 和 m-1 之间，距离为 1，而不是 m-1。 

另一种边缘情况是所有人都集中在一个位置时。 那么最好的交汇点就是那个位置，成本为零。 天真的平均直觉（比如选择一条线上的中点）在不处理圆形环绕的情况下不会直接转换。 

## 方法

 暴力解决方案固定每个可能的会议建筑物 h，并通过求和从每个 a[i] 到 h 的最短圆形距离来计算总距离。 动态计算距离为 O(1)，因此每个 h 的成本为 O(n)，总共为 O(nm)。 当 m 达到 2 × 10^5 时，在最坏的情况下达到 4 × 10^10 次操作，这远远超出了限制。 

一旦我们不再将圆视为一个圆，而是“展开”它，结构就变得易于管理。 如果我们固定一个参考点并对所有位置进行排序，我们可以想象将它们放在一条线上。 对于固定候选 h，每个点贡献 min(|a[i] − h|, m − |a[i] − h|)。 困难在于最小值内的绝对值，它会根据我们是顺时针还是逆时针移动而改变行为。 

一个关键的观察结果是，最优 h 必须位于圆上，这样当我们旋转坐标系时，问题就相当于使用特殊的加倍技巧来最小化一条直线上的绝对偏差之和。 我们可以通过为每个 ai 添加 ai + m 来复制该数组，对其进行排序，并将圆视为长度为 2m 的线性段。 那么任何长度为 m 的圆间隔都对应于圆的有效“切割”。 

对于已排序的双倍数组中的固定起点，我们考虑大小为 n 的窗口（或基于 m 的投影，具体取决于公式），并使用前缀和评估该结构内的最佳交汇点。 这减少了重复的重新计算，并允许在预处理后以 O(1) 的时间评估每个候选窗口。 

因此，最佳解决方案依赖于双坐标系上的排序和前缀和，将圆形距离最小化转换为重复的线性中值类型优化。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了|
 | 排序+前缀和+循环展开 | O(n log n + n) | O(n log n + n) | O(n) | 已接受 |

 ## 算法演练

 我们通过以 m 的偏移量复制每个位置，将圆形位置转换为线性表示。 这使我们能够将环绕间隔表示为连续的段。

然后我们对这个大小为 2n 的扩展列表进行排序。 

接下来，我们预先计算前缀和，以便我们可以在 O(1) 中查询任何段的和。 

我们在排序数组上滑动一个大小为 n 的窗口。 每个窗口代表圆的一个候选“切口”，这意味着我们将该窗口内的点解释为从该切口开始的圆的线性化版本。 

对于每个窗口，我们都会考虑在该段内选择最佳的交汇点。 在一条线上，绝对偏差之和在中值处最小。 因此，在每个窗口内，我们将中位数视为最佳候选交汇点。 

我们使用前缀和来计算使窗口中的所有点在中位数处相交的成本：左侧贡献 (median * count − sum_left)，右侧贡献 (sum_right −median * count)。 

我们对所有窗口取最小值。 

### 为什么它有效

 交汇点的任何圆形选择都对应于将圆切割成线性段。 通过复制数组，每个这样的切割都被表示为一个连续的窗口。 在任何固定窗口内，绝对距离的最佳交汇点是中值，并且前缀和允许快速评估。 由于每个有效的循环配置在某个窗口中只表示一次，因此所有窗口的最小值与全局最优值相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    a.sort()

    # duplicate to handle circular wrap
    b = a + [x + m for x in a]

    prefix = [0] * (2 * n + 1)
    for i in range(2 * n):
        prefix[i + 1] = prefix[i] + b[i]

    def range_sum(l, r):
        return prefix[r] - prefix[l]

    ans = float('inf')

    for i in range(n):
        j = i + n

        mid = i + n // 2

        median = b[mid]

        left_count = mid - i
        left_sum = range_sum(i, mid)

        right_count = j - mid
        right_sum = range_sum(mid, j)

        cost_left = median * left_count - left_sum
        cost_right = right_sum - median * right_count

        ans = min(ans, cost_left + cost_right)

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先对位置进行排序，以便循环结构在复制后变得易于管理。 数组 b 包含原始点和移位点，允许任何环绕段显示为连续间隔。 

前缀和支持恒定时间范围和查询，这对于有效评估每个候选窗口是必要的。 

对于大小为 n 的每个窗口，我们选择中值索引作为最小化绝对偏差的最佳交汇点。 成本公式围绕中位数分为左贡献和右贡献，两者都使用前缀和计算以避免重复迭代。 

该循环检查所有 n 个可能的窗口，确保考虑每个圆形切割。

import sys, io

def run(inp: str) -> str:

    import sys

    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

        prefix[i + 1] = prefix[i] + b[i]

    for i in range(n):
        j = i + n
        mid = i + n // 2
        median = b[mid]

        left = median * (mid - i) - range_sum(i, mid)

 ## 边缘情况

 单个参与者的情况是最简单的边界。 该算法仍然形成大小为 1 的窗口，中值是唯一的元素，并且两个前缀贡献都变为零，从而产生正确的输出。 

当所有参与者都在同一栋大楼时，排序和复制会保留相同的值。 每个窗口的方差为零，因此每个成本都为零。 最小值保持为零，与预期结果相符。 

对于重环绕输入（例如接近 0 和接近 m − 1 的位置），复制可确保它们在至少一个窗口中显示为相邻。 在该窗口中，中位数正确反映了圆形边界上的最佳交汇点，避免了将 0 和 m − 1 视为在一条直线上相距较远的陷阱。
