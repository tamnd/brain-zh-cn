 ## 解决方案
 ## 问题理解

 有几种食物最初放置在垂直平面上的整数坐标处，所有这些食物都直接落向地线$y = 0$。 每一秒，每个食物都会向下移动一个单位，同时保持其水平位置不变。 单个角色从地面的原点开始，可以以每秒一个单位的速度向左、向右移动或保持原地。 

食物只有在到达地面的那一刻才可以食用。 只有当角色同时站在同一水平坐标上时，他才能吃掉它。 如果他提前或迟到，食物就会丢失。 

任务是通过选择最佳的运动时间表和选择目标食物来确定可以食用的最大食物数量。 

输入最多提供 2000 个食物项，每个食物项由一个位置描述$(x_i, y_i)$。 食物到达地面的时间是固定的，等于$y_i$，因为它每秒减少一。 因此，每种食物都可以被重新解释为对位置的请求$x_i$在某个时间$y_i$。 

这将问题转化为选择尽可能多的请求，其中每个请求都有时间和位置，并且请求之间的移动受到线路上单位速度的限制。 

主要的困难是并不是每对食物的顺序都是相容的。 即使一种食物出现的时间较早，在剩余时间内从物理位置移动到另一种食物的位置也可能是不可能的。 

一个天真的错误是认为按时间排序就足够了，并且总是贪婪地获取可到达的食物是有效的。 例如，考虑：

 输入：

 3

 0 1

 100 2

 1 2

 第一份食物是在$(0,1)$，第二个在$(100,2)$，第三个在$(1,2)$。 优先考虑最早可达的贪婪选择可能会错误地选择$(0,1)$然后尝试$(100,2)$，由于距离原因不可能，缺少有效链$(0,1) \rightarrow (1,2)$。 

另一个失败案例来自于忽视等待灵活性。 即使某个食物可以从源头到达，跳过它以到达更多后续食物可能仍然会更好。 

由于这些依赖性，该结构本质上是度量约束下的最长可行链问题。 

## 方法

 每个食物项目都可以被视为一个点$(t_i, x_i)$， 在哪里$t_i = y_i$。 我们需要选择这些点的最大子集，以便我们可以以递增的时间顺序遍历它们，从$(0, 0)$，其约束是在连续选定点之间移动遵循单位速度。 

两种所选食物之间的运动限制$i$和$j$， 和$t_i < t_j$， 是：$$|x_i - x_j| \le t_j - t_i$$这确保了 Pou 可以在可用时间内在两个位置之间移动。 

强力解决方案会尝试所有子集或所有路径。 对于每种食物，我们尝试决定是否将其包含在之前的每种兼容食物之后。 这导致检查所有点对之间的转换并有效地探索所有链。 虽然正确性很简单，但子集的数量是指数级的，甚至成对探索也是如此$O(n^2)$但如果没有记忆，很快就会退化为递归公式中的重复重新计算。 

关键的观察是，一旦食物按时间排序，问题就变成有向无环图中的最长路径，其中每个节点代表食物，边代表在它们之间移动的可行性。 由于时间严格增加，因此不存在循环，因此动态规划可以干净地应用。 

我们为每种食物定义一个 DP 状态：可以食用的最佳数量正好以该食物结尾。 每个状态仅取决于较早的时间，因此我们可以按升序计算它。 

这将问题从探索指数子集减少到一次评估所有成对转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集或路径进行强力搜索 | 指数| O(n) 到 O(n^2) | 太慢了|
 | DP 排序事件 | O(n^2) | O(n^2) | O(n) | 已接受 |

 ## 算法演练

 1. 将每种食物转化为一个事件$(t_i, x_i)$， 在哪里$t_i = y_i$。 这将问题重新定义为时间安排点，而不是明确地跟踪下落运动。 
2. 按时间递增对所有事件进行排序。 这确保了任何有效的转换总是从较早的索引到较晚的索引，因此我们永远不需要重新访问状态。 
3. 初始化一个DP数组，其中$dp[i]$代表在事件恰好结束时可以吃的最大食物数量$i$。 
4. 对于每个事件$i$，首先检查是否可以从原点直接到达。 这是有效的，如果$|x_i| \le t_i$。 如果是这样，设置$dp[i] = 1$，否则将其初始化为零。 这捕获了从该食物开始连锁的可能性。 
5. 对于每对事件$j < i$,检查事件是否$i$可以关注事件$j$。 如果满足以下条件，则转换有效：$$|x_i - x_j| \le t_i - t_j$$如果有效，则更新：$$dp[i] = \max(dp[i], dp[j] + 1)$$此步骤通过扩展先前的最佳链来构建更长的可行序列。 

1. 答案是所有值中的最大值$dp[i]$。 

其工作原理是，任何可行的食物序列都精确对应于每个连续对满足运动约束的点序列。 按时间排序可确保每个有效序列都在此 DP 图中显示为路径，并且 DP 递归会探索所有此类路径而不重复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    foods = []
    for _ in range(n):
        x, y = map(int, input().split())
        foods.append((y, x))
    
    foods.sort()
    
    dp = [0] * n
    ans = 0
    
    for i in range(n):
        t_i, x_i = foods[i]
        
        if abs(x_i) <= t_i:
            dp[i] = 1
        
        for j in range(i):
            t_j, x_j = foods[j]
            
            if dp[j] > 0 and abs(x_i - x_j) <= t_i - t_j:
                dp[i] = max(dp[i], dp[j] + 1)
        
        ans = max(ans, dp[i])
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先将每个项目重新解释为时间位置事件并按时间对它们进行排序。 DP 数组是增量构建的，其中每个状态要么在可从原点到达的情况下启动一个新链，要么在移动约束允许时扩展先前的链。 

一个微妙的细节是从食物开始的初始化条件。 无需检查$|x_i| \le t_i$，DP 会错误地认为 Pou 可以“传送”到早期食物。 这个条件从一开始就加强了可行性。 

嵌套循环是安全的，因为$n \le 2000$， 制作$n^2$在时限内可行的过渡。 

## 工作示例

 考虑一个小例子：

 输入：

 3

 0 1

 1 2

 2 4

 转换和排序后：

 | 我| 时间$t$| 位置$x$| dp 初始化 | 过渡|
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 0 | 1 | 开始有效|
 | 1 | 2 | 1 | 1 | 从 0 开始有效 |
 | 2 | 4 | 2 | 1 | 从 1 有效 |

 为了$i=1$, 过渡自$i=0$成立，因为$|1-0| \le 1$。 为了$i=2$，之前的两个状态在顺序上是兼容的，但是最好的链是$0 \rightarrow 1 \rightarrow 2$，给定 dp = 3。 

这表明 DP 正在累积最长的物理上可实现的运动链。 

另一个例子：

 输入：

 3

 0 1

 100 2

 1 2

 排序后：$(1,0), (2,1), (2,100)$| 我| dp值| 最佳前任 |
 | --- | --- | --- |
 | 0 | 1 | 开始 |
 | 1 | 2 | 0 |
 | 2 | 2 | 0 |

 这里大跳转到$x=100$由于距离限制，无法遵循较早的状态，因此它永远不会在整个链上得到改进$0 \rightarrow 1$。 这证实了 DP 正确地拒绝了物理上不可能的转换。

 ## 边缘情况

 一种边缘情况是无法从源头到达任何食物。 例如：

 输入：

 2

 100 1

 200 2

 每一项都违反$|x| \le t$，因此 DP 值始终保持为零。 该算法正确输出零，因为从未创建有效的起始状态。 

另一个边缘情况是食物可以从源头单独到达，但顺序互不兼容。 DP 确保了正确性，因为它仅在成对时间距离约束成立时才扩展链。 任何无效的转换自然都会被忽略，从而防止过度计数。 

最后一个边缘情况涉及同时吃多种食物。 由于排序组的次数相等，因此从不考虑同一时间内的转换，因为$t_j < t_i$是必须的。 这可以防止相同时间戳下的非法“即时跳转”。
