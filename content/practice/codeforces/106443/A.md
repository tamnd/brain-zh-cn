 ## 解决方案
 ## 问题理解

 我们被要求计算有多少种不同的方式可以构建参与者序列，这些参与者对“有趣分数”的个人贡献加起来正好达到给定的目标值$D$。 每个参与者在正常状态下贡献 1 个单位的乐趣，如果通过 AI 增强则贡献 2 个单位。 这些参与者在照片中出现的顺序很重要，但参与者本身是无法区分的，这意味着只有贡献的模式很重要，而不是身份。 

所以问题归结为计算有多少个由 1 和 2 组成的有序序列的总和正好等于$D$。 每个有效序列对应于正常参与者和增强参与者的不同排列。 

输入是单个整数$D$，输出是此类序列的数量对 2026 求模。 

约束条件$D \le 10^6$立即排除序列的任何指数计数。 即使是天真的回溯方法也会粗略地探索$2^D$最坏情况下的可能性，远远超出了可行的限度。 解决方案必须在线性或接近线性的时间内运行。 

一个微妙的点是模 2026 不是素数模。 这消除了我们可以安全地使用模逆或二项式系数公式而无需考虑因式分解的任何期望。 任何组合封闭形式方法都是脆弱的。 动态规划公式完全避免了这个问题。 

边缘情况出现在较小的值$D$。 例如，当$D = 1$，只有一个序列：$[1]$。 什么时候$D = 2$，有两个序列：$[1+1]$和$[2]$。 简单的递归方法经常会由于重复计算顺序或忘记小深度的分支选择之一而出现错误计数。 

## 方法

 思考问题最直接的方法就是生成所有 1 和 2 的序列，其和为$D$。 在每一步中，我们要么放置 1 并将剩余的总和减少 1，要么放置 2 并将其减少 2。 这自然会导致递归。 

如果我们定义$f(x)$作为有效序列的数量总和$x$，那么每个有效的 sum 序列$x$必须以 1 或 2 结尾。如果以 1 结尾，则前缀是任何有效的 sum 序列$x-1$。 如果以 2 结尾，则前缀是任意有效的 sum 序列$x-2$。 这给出了一个重现$f(x) = f(x-1) + f(x-2)$。 

简单的递归实现直接遵循这个定义。 但是，它会重复重新计算相同的值。 例如，计算$f(D)$扩展到$f(D-1)$和$f(D-2)$，两者都再次扩展到重叠的子问题。 这导致计算量呈指数增长，大致与没有记忆的斐波那契递归成正比。 

关键的观察结果是，该结构与移动一个索引的斐波那契序列相同。 我们不是重新计算子问题，而是从下到上增量存储结果。 由于每个状态仅取决于前两个状态，因此我们只需要线性时间来计算所有值$D$。 

这将问题从指数递归转换为简单的迭代动态程序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力递归 |$O(2^D)$|$O(D)$| 太慢了|
 | 动态规划|$O(D)$|$O(1)$| 已接受 |

 ## 算法演练

 我们计算从 0 到 的所有总和的有效序列数$D$，逐步构建答案。 

1. 定义一个函数$f(x)$表示总和为的有效序列的数量$x$。 这将问题重新构建为使用大小为 1 或 2 的步长来计算达到目标总和的方法。 
2. 初始化基本案例。 为了$x = 0$，只有一种方法：什么都不选择。 为了$x = 1$，只有一种方法：单一 1。这些基本情况锚定重现。 
3. 从 2 迭代到$D$。 在每个值$x$, 计算$f(x)$使用递归$f(x) = f(x-1) + f(x-2)$，因为任何有效序列结束于$x$必须来自将 1 附加到以下解决方案$x-1$或 2 的解$x-2$。 
4. 每次加法时应用模 2026 以保持值有界并防止溢出。 这不会影响正确性，因为模运算保留了加法结构。 
5. 返回$f(D)$作为最终答案。 

### 为什么它有效

 正确性来自于每个有效序列的结构分解。 任意序列总和为$x$必须恰好以两种不相交情况之一结束：最后一个元素为 1 或最后一个元素为 2。这些情况划分解空间而不重叠。 递归对每个分区精确计数一次，基本情况确保递归从明确定义的最小结构开始。 由于每个较大的解决方案都是由较小的解决方案独特构建的，因此不会遗漏或重复计算任何配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 2026

def solve():
    D = int(input().strip())
    
    if D == 0:
        print(1)
        return
    if D == 1:
        print(1)
        return

    prev2 = 1  # f(0)
    prev1 = 1  # f(1)

    for _ in range(2, D + 1):
        cur = (prev1 + prev2) % MOD
        prev2, prev1 = prev1, cur

    print(prev1)

if __name__ == "__main__":
    solve()
```该实现仅保留两个滚动变量而不是完整的 DP 数组，因为每个状态仅取决于前两个状态。 初始化与基本情况匹配$f(0) = 1$和$f(1) = 1$。 该循环迭代地建立递归。 

一个常见的错误是错误地移动索引，例如从$f(1) = 0$或者忘记需要空序列作为正确组合计数的基础。 

## 工作示例

 考虑$D = 4$。 有效的序列是：$[1,1,1,1]$,$[2,1,1]$,$[1,2,1]$,$[1,1,2]$,$[2,2]$。 

我们一步步计算：

 | x| f(x-2) | f(x-2) | f(x-1) | f(x-1) | f(x) | f(x) |
 | --- | --- | --- | --- |
 | 0 | - | - | 1 |
 | 1 | - | - | 1 |
 | 2 | 1 | 1 | 2 |
 | 3 | 1 | 2 | 3 |
 | 4 | 2 | 3 | 5 |

 这证实了$f(4) = 5$，匹配枚举。 

现在考虑$D = 5$:

 | x| f(x-2) | f(x-2) | f(x-1) | f(x-1) | f(x) | f(x) |
 | --- | --- | --- | --- |
 | 3 | 1 | 2 | 3 |
 | 4 | 2 | 3 | 5 |
 | 5 | 3 | 5 | 8 |

 所以有8种配置$D = 5$，与斐波那契增长一致。

 ## 边缘情况

 对于$D = 0$，算法显式返回 1，表示空配置。 循环被跳过，因此不会访问无效状态。 

为了$D = 1$，函数直接返回1，匹配单个有效配置$[1]$。 

为了$D = 2$，循环运行一次并计算$f(2) = 2$，源自$f(1) + f(0)$, 正确产生$[1+1]$和$[2]$。 滚动变量确保不会发生相差一位的变化。 

这些案例证实初始化和循环对齐在整个输入范围内都是一致的。
