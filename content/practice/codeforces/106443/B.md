 ## 解决方案
 ## 问题理解

 给定两个长度相等的整数序列。 一个序列属于德雷克斯，另一个序列属于老板。 在任何交互发生之前，德雷克斯可以自由地排列他自己的序列。 固定排列后，两个序列按索引对齐，总损伤计算为配对元素之间的绝对差之和。 

任务是选择德雷克斯序列的排序，以使这个总和尽可能小。 

关键的结构细节是只有 Drex 的数组是可重新排序的。 boss 的数组是固定的，所以问题本质上是如何以最佳方式配对两个多重集的元素。 

约束 n 高达 2 × 10^5 立即排除任何二次配对策略。 任何尝试所有匹配或什至贪婪地尝试没有结构的本地交换的解决方案在最坏的情况下都会失败，因为可能的排列数量呈阶乘增长。 

当人们认为配对相等的索引或进行简单的贪婪扫描就足够时，就会出现一种常见的故障模式。 例如，如果德雷克斯有`[10, 1, 100]`老板有`[2, 50, 60]`，按原始顺序配对会产生很大的成本，并且没有排序洞察力的本地交换可能仍然会错过全局最优配对。 

另一个微妙的边缘情况是当值严重倾斜时：总是与最接近的剩余值匹配而没有全局排序的天真贪婪可能会陷入次优的早期选择。 例如，德雷克斯`[1, 100, 101]`和老板`[2, 3, 200]`需要全局一致的排序而不是局部最优的配对决策。 

这些问题表明问题不在于局部匹配，而在于排序结构的全局对齐。 

## 方法

 暴力破解的想法很简单：尝试 Drex 数组的每个排列，计算与 boss 数组的绝对差值总和，并取最小值。 这是正确的，因为它明确地评估了排列引起的所有可能的配对。 然而，排列的数量为 n!，每次评估的成本为 O(n)，给出 O(n · n!) 次操作，即使 n 约为 10，这也是不可行的。 

为了改进这一点，我们观察到 boss 数组是固定的，我们只控制 Drex 的值如何分配给位置。 绝对值成本提出了一种几何解释：我们试图在一维中以最小 L1 匹配成本来匹配数轴上的两个点集。 

在一维中，最小化总绝对差的最佳策略是将已排序元素与已排序元素配对。 这是有效的，因为配对中的任何反转都可以被证明是可以改进的：如果两对按排序顺序交叉，交换它们永远不会增加成本，而且通常会降低成本。 这是线路上最佳匹配的经典交换论证。 

因此，我们没有尝试排列，而是对两个数组进行排序并将元素 i 与元素 i 进行匹配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n·n!) | O(n·n!) | O(n) | 太慢了|
 | 最优（排序+配对）| O(n log n) | O(n log n) | O(1) 或 O(n) | 已接受 |

 ## 算法演练

 我们依赖这样一个事实：当两个序列的排序一致时，配对就会变得最佳。 

### 步骤

 1. 读取 n，两个数组的大小。 
2.读取Drex的数组和boss的数组。 
3. 按非降序对两个数组进行排序。 

排序强制执行全局结构，以便小值与小值对齐，大值与大值对齐。 
4. 将总伤害的累加器初始化为零。 
5. 从 0 迭代 i 到 n − 1。 
6. 对于每个指标 i，将第 i 个最小的 Drex 值与第 i 个最小的 boss 值之间的绝对差相加。 
7. 输出累加和。 

关键决策是第 3 步。如果不对两个数组进行排序，任何贪婪配对都会在局部决策不反映全局最优性的空间中进行操作。 排序将问题转化为单调匹配问题。 

### 为什么它有效

 排序后，两个序列都在同一轴上排序。 如果存在一对索引 i < j，使得 Drex[i] 与 boss[j] 配对，并且 Drex[j] 与 boss[i] 配对，则交换这些配对不会增加总成本。 这是因为直线上的绝对值距离满足匹配中相交的边总是可以不相交的性质，而不会使总长度恶化。 重复应用此参数会删除配对之间的所有反转，强制将排序数组上的恒等配对作为最佳解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    d = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    d.sort()
    b.sort()
    
    ans = 0
    for i in range(n):
        ans += abs(d[i] - b[i])
    
    print(ans)

if __name__ == "__main__":
    solve()
```一旦理解了排序原理，实现就很直接了。 主要的微妙之处是确保两个数组在配对之前独立排序。 一个常见的错误是仅对 Drex 的数组进行排序或尝试部分对齐而不进行完全排序，这会破坏正确性所需的单调结构。 

累加使用标准循环，因为 n 可能很大，但 Python 的整数算术可以轻松处理潜在的总和大小，因为值的大小最多可达 2 × 10^14。

 ## 边缘情况

 关键的边缘情况是两个数组包含相同的多重集但顺序不同。 例如：```
n = 5
d = [4, 1, 3, 2, 5]
b = [1, 2, 3, 4, 5]
```对两者进行排序会得到相同的数组，并且该算法产生零成本。 没有排序的天真贪婪可能会提前将 4 与 1 配对，并且永远不会恢复最佳对齐，从而导致不必要的成本积累。 

另一种情况是极端传播：```
n = 3
d = [-100, 0, 100]
b = [-50, -49, 200]
```排序后：

 d = [-100, 0, 100]

 b = [-50, -49, 200]

 按索引配对会产生：

 50 + 49 + 100 = 199

 相反，如果尝试在没有全局排序的情况下在本地匹配最接近的值，则可能会错误地将 100 与 -50 提前配对，从而使 -100 与 200 配对，从而产生更大的总数。 排序配对通过强制全局单调对​​齐来避免这种情况，确保最终匹配中不存在交叉配对。
