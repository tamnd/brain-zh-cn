 ## 解决方案
 ## 问题理解

 我们得到一个方形网格，其中恰好有两个单元格已经标有星星。 这两颗星是我们开始时唯一的信息，它们定义了网格上的部分几何形状。 我们的任务是准确放置两颗额外的星星，使四颗星星成为轴对齐矩形的顶点。 

我们构建的矩形的边必须与网格线平行，这意味着它的角纯粹通过选择两行和两列来确定。 关键的约束是现有的两个星星必须是该矩形的一部分，并且只要生成的形状是网格边界内的有效矩形，我们就可以自由选择其他两个角。 

输出只是添加两个缺失的星星后的最终网格。 我们没有被要求优化任何东西或计算可能性，只是为了产生任何有效的完成。 

约束足够小，即使每个测试用例直接线性扫描网格也足够了。 按维度总和计算，所有测试用例中的单元总数最多为 400，因此每个测试用例的 O(n²) 方法足够快。 这立即排除了任何比直接网格处理更复杂的事情，并表明解决方案应该依赖于直接坐标推理而不是搜索。 

当两个给定的星星排列在同一行或同一列时，就会出现微妙的边缘情况。 在这种情况下，矩形会退化为必须通过选择不同的行或列来扩展一个维度的情况。 总是假设不同的行和列而不处理相等性的天真的方法在这里会失败。 

例如，如果两个星星位于同一行，例如位置 (1, 1) 和 (1, 4)，则矩形必须使用不同的行，并且缺失的星星直接放置在它们的下方。 类似地，如果两颗星共用一列，则矩形水平延伸。 

## 方法

 思考这个问题的一种强力方法是尝试可以定义矩形的每对可能的行和列，并检查给定的星星是否可以作为其两个角。 对于每个候选矩形，我们将验证其角是否匹配约束，然后在找到后输出有效的配置。 这是可行的，因为任何轴对齐的矩形都是通过选择两个不同的行和两个不同的列来完全确定的。 

然而，即使网格很小，这种方法在概念上也不必要地昂贵。 更重要的是，它隐藏了问题的结构。 给定的两个星星已经固定了两个坐标，并且矩形必须与它们对齐。 这意味着正确的矩形不是我们全局搜索的东西，而是星星位置直接暗示的东西。 

关键的观察是矩形是通过独立配对 x 坐标和 y 坐标来定义的。 如果两颗星位于 (r1, c1) 和 (r2, c2) 处，则缺失的角点一定是 (r1, c2) 和 (r2, c1)，除非 r1 等于 r2 或 c1 等于 c2。 在那些退化的情况下，我们引入新的行或列，同时保持相同的结构。 

这将问题简化为简单的坐标处理，而不是任何组合搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有矩形进行暴力破解 | O(n⁴) | O(1) | O(1) | 概念上太慢|

 ## 算法演练

 我们独立处理每个测试用例。

1. 首先，扫描网格找到现有的两颗星星的坐标。 我们将它们存储为 (r1, c1) 和 (r2, c2)。 此步骤是必要的，因为输入是位置的而不是基于坐标的。 
2. 检查两颗星是否位于不同行和不同列。 如果行和列都不同，我们就已经有了矩形的对角线。 在这种情况下，缺失的角自然位于 (r1, c2) 和 (r2, c1) 处，因为矩形独立地保留行和列配对。 
3. 如果星星共享同一行，我们不能仅通过交换列来形成矩形，因为那样会折叠成一条线。 相反，我们选择不同的行。 如果共享行不为 0，我们可以安全地选择第 0 行，否则我们选择第 1 行。然后我们将星星放在 (new_row, c1) 和 (new_row, c2) 处，垂直完成矩形。 
4. 如果星星共享同一列，我们应用对称的想法。 我们选择不同的列，如果可能的话通常为 0，否则为 1，并将星号放在 (r1, new_col) 和 (r2, new_col) 处。 
5.最后，我们输出修改后的网格。 

步骤 3 和 4 中的关键决定是我们有意引入一个与共享维度正交的新坐标。 这保证了矩形有效，同时保持在边界内，因为 n 至少为 2。 

### 为什么它有效

 正确性来自于以下事实：任何轴对齐的矩形都是在行和列维度上独立确定的。 如果两个坐标不同，则矩形由配对端点唯一形成。 如果一个坐标相同，则矩形必须在缺失的维度上延伸，并且由于 n ≥ 2，始终存在至少一个替代索引。这保证了我们始终可以构造两个新的角来完成有效的矩形，而不会违反边界或覆盖结构约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    g = [list(input().strip()) for _ in range(n)]

    stars = []
    for i in range(n):
        for j in range(n):
            if g[i][j] == '*':
                stars.append((i, j))

    (r1, c1), (r2, c2) = stars

    if r1 != r2 and c1 != c2:
        g[r1][c2] = '*'
        g[r2][c1] = '*'
    elif r1 == r2:
        nr = 0 if r1 != 0 else 1
        g[nr][c1] = '*'
        g[nr][c2] = '*'
    else:
        nc = 0 if c1 != 0 else 1
        g[r1][nc] = '*'
        g[r2][nc] = '*'

    for row in g:
        print("".join(row))
```实现首先读取网格并提取两个星星的位置。 这种显式提取很重要，因为它允许我们纯粹在坐标中进行推理，而不是重复扫描网格。 

三格结构直接反映了矩形的几何形状。 第一种情况处理一般对角线情况。 当沿行或列对齐时，第二种和第三种情况处理简并性。 

唯一微妙的实现细节是选择有效的替代行或列。 因为 n 至少为 2，所以只要我们避开原始坐标，选择 0 或 1 总是安全的。

 ## 边缘情况

 当两颗星已经排成一行时，构造必须避免将同一行重复用于缺失的角。 该算法显式切换到另一行，保证存在，因为网格至少有两行。 这可以防止将矩形折叠成一条线。 

当两颗恒星共享同一列时，相同的逻辑对称地适用。 选择任何其他列就足够了，索引 0 和 1 之间的简单选择即可确保正确性，而无需搜索。 

在所有情况下，生成的坐标都保持在边界内并保留矩形属性，因为每个轴都是独立处理的。
