 ## 解决方案
 ## 问题理解

 我们被要求确定帖木儿在马拉松比赛中相对于其他三名跑步者的位置。 每个测试用例提供四个不同的整数：首先是 Timur 的距离，然后是其他三个参与者跑的距离。 任务是计算有多少跑步者跑的距离严格超过 Timur。 

该问题的结构很简单，但理解边界很有用。 每个距离在 0 到 10,000 之间，最多可以有 10,000 个测试用例。 这告诉我们，我们需要一个与测试用例数量成线性关系的解决方案，因为即使是小型四元素数组的 O(n²) 在技术上也是可以接受的（因为 4² 是微不足道的），但如果我们编写的代码尝试在测试用例之间进行不必要的比较，它可能会变得低效。 

需要注意的边缘情况是当帖木儿跑出四个距离中的最大距离或最小距离时。 例如，如果 Timur 跑了 10,000，其他人跑了 0、1、2，则正确的输出为零。 如果假设 Timur 始终是第一个或最后一个，粗心的解决方案可能会尝试使用排序并错误地获取索引。 另一个微妙的边缘是，当其他参与者的距离围绕 Timur 的距离形成连续序列时，例如 3、4、5、2，而 Timur 为 4。粗心的逻辑可能会错误地计算严格领先的参与者与并列或落后的参与者。 

## 方法

 最幼稚的方法是分别检查帖木儿与其他三个参与者的距离。 将计数器初始化为零，迭代三个距离，并在每次发现大于 Timur 的值时增加计数器。 这种强力方法之所以有效，是因为我们只有其他三个数字可供比较，因此最坏的情况是我们对每个测试用例进行三次比较。 给定 10,000 个测试用例，这相当于 30,000 次比较 - 对于任何现代 CPU 来说都是微不足道的。 蛮力是正确的，这里不关心速度。 

优化的关键见解（尽管不是严格必要的）是认识到列表的大小始终为 4。 我们可以对这四个数字进行排序，直接找到帖木儿的排名。 对四个数字进行排序也很简单，但它比简单的三个比较方法引入了更多的操作。 排序在概念上更重，因此为了清晰和最小的开销，比较方法是首选。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个测试用例 O(1) | O(1) | O(1) | 已接受 |
 | 基于排序 | 每个测试用例 O(4 log 4) | O(1) | O(1) | 已接受但没有必要 |

 结论是，最简单的方法也是最佳的：计算三个距离中有多少个距离超过 Timur 的距离。 

## 算法演练

 1.读取测试用例的数量。 
2. 对于每个测试用例，读取四个距离，将 Timur 的距离存储在一个变量中，将其他距离存储在列表中。 
3. 将计数器初始化为零。 该计数器将跟踪 Timur 之前的参与者数量。 
4. 迭代其他三个距离的列表。 对于每个距离，检查它是否严格大于 Timur 的距离。 如果是，则增加计数器。 
5. 检查完所有三个参与者后，输出计数器。 这是帖木儿领先的跑步人数。 

工作原理：该算法保持一个简单的不变量：在迭代中的任何一点，计数器准确地反映了到目前为止处理的参与者有多少人跑得比 Timur 更远。 到最后，它会正确计算所有领先的参与者，而不会存在错误计算帖木儿后面的联系或距离的风险。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, c, d = map(int, input().split())
    counter = 0
    for distance in (b, c, d):
        if distance > a:
            counter += 1
    print(counter)
```该代码首先读取测试用例的数量。 对于每个测试用例，我们直接解压四个整数。 仅当严格领先于 Timur 的参与者时，计数器才会递增。 对其他三个距离使用元组可以使迭代简洁并避免创建临时列表。 比较是简单的整数，因此不存在溢出或精度问题的风险。 

## 工作示例

 **样品1**

 输入：`2 3 4 1`帖木儿的距离`a = 2`。 其他距离是`3, 4, 1`。 

| 距离 | 柜台 |
 | --- | --- |
 | 3 | 1 |
 | 4 | 2 |
 | 1 | 2 |

 输出：`2`。 该表显示了我们如何为 Timur 之前的参与者增加计数器，并为后面的参与者保持不变。 

**样品2**

 输入：`500 600 400 300`帖木儿的距离`a = 500`。 其他距离是`600, 400, 300`。 

| 距离 | 柜台 |
 | --- | --- |
 | 600 | 1 |
 | 400 | 1 |
 | 300 | 300 1 |

 输出：`1`。 只有距离 600 的跑步者领先。 这证实了该算法可以正确处理 Timur 上方和下方的距离。

 ## 边缘情况

 当 Timur 跑出四个人中的最大距离时，例如，`10000 0 1 2`，迭代检查`0 > 10000`,`1 > 10000`,`2 > 10000`，全是假的。 计数器保持为零，产生正确的输出。 当 Timur 跑完最短距离时，例如，`0 1 2 3`，每次比较都会增加计数器，产生`3`，与前面的参与者数量相匹配。 

即使数字在 Timur 距离附近是连续的，例如`4 3 5 2`，该算法仅计算那些严格大于 (`5`），正确返回`1`。 不需要排序或额外的数据结构来处理这些边缘情况，因为我们根据 Timur 的距离明确检查每个值。 

这篇社论确保读者可以根据第一原则进行推理：将 Timur 与每个参与者进行比较并计算前面的数字，这对于问题大小来说既正确又最佳。
