 ## 解决方案
 ## 问题理解

 我们给出了 24 小时制的开始时间和观察之间固定的分钟数。 从给定的时间开始，维克多每次都重复地看时钟。$x$分钟。 

由于 24 小时时钟一天后会绕一圈，因此显示时间的顺序最终会变成周期性的。 我们必须计算这个重复序列中出现了多少个**不同的回文时间**。 

时间写为`"HH:MM"`。 为了检查它是否是回文，我们处理整个字符串，包括冒号。 例如，`"12:21"`和`"05:50"`是回文，因为向后读取五个字符的字符串会得到相同的字符串。 

限制非常小。 一个时钟只包含$24 \times 60 = 1440$独特的时刻。 不论其价值$x$，在最多 1440 次转换之后，我们必须返回到之前看到的时间。 最多有 100 个测试用例，即使对每个测试用例处理全部 1440 次也只需要大约 144,000 次迭代，这是微不足道的。 

主要挑战不是性能，而是正确处理循环结构。 

一个容易犯的错误是计算回文出现次数，而不是计算不同的回文时间。 考虑：```
11:11 1440
```每一次观察都表明`11:11`，但答案是`1`，不是无限计数，也不是观察次数。 

另一个常见错误是模拟正好 1440 分钟，而不是直到序列重复为止。 例如：```
00:00 720
```顺序是：```
00:00 -> 12:00 -> 00:00
```只达到了两个不同的时间。 当起始状态再次出现时，正确的解决方案就会停止。 

第三个微妙的问题是在午夜处理环绕。 例如：```
23:59 1
```添加一分钟应该会产生`00:00`， 不是`24:00`。 以总分钟数模 1440 工作可以完全避免此类错误。 

## 方法

 最直接的想法就是将时钟反复推进$x$分钟并记录每次遇到的情况。 每当显示的时间是回文时，我们就把它添加到集合中。 一旦我们返回到之前访问过的时间，该过程就会停止。 

这种暴力模拟已经足够快了。 状态空间仅包含 1440 个可能的时钟值，因此每个测试用例模拟最多执行 1440 次迭代。 

由于序列是循环的，不那么小心的暴力破解可能会无限期地持续下去。 关键的观察结果是时钟状态完全由当天的当前分钟决定。 由于仅存在 1440 个状态，因此重新访问一个状态意味着整个未来序列将完全重复。 

一旦我们意识到该进程的生命周期最多为 1440 个状态，解决方案就变得简单了。 我们模拟该序列，存储访问次数，并对一个完整周期内遇到的不同回文字符串进行计数。 

由此产生的算法对于给定的约束既简单又最优。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 整个周期的强力模拟 | 欧(1440) | 欧(1440) | 已接受 |
 | 最佳循环模拟| 欧(1440) | 欧(1440) | 已接受 |

 在此问题中，强力方法和最优方法实际上是相同的，因为整个状态空间仅包含 1440 个可能的时间。 

## 算法演练

 1.转换起始时间`"HH:MM"`为自午夜以来的分钟数。 
2. 创建一组访问过的时钟状态。 这将使我们能够检测序列何时开始重复。 
3. 为回文时间创建另一组。 使用集合可以保证每个回文数仅计算一次，即使它在循环中出现多次。 
4. 当当前时钟状态没有被访问过时：

 将状态添加到访问集中。 
5. 将当前分钟数转换回`"HH:MM"`格式。 
6. 检查结果字符串是否为回文。 

如果是，则将其插入到回文集中。 
7. 将时钟提前$x$分钟以 1440 为模。 

模运算自动处理午夜的环绕。 
8. 当达到先前访问的状态时，停止模拟。 
9.输出回文集的大小。 

### 为什么它有效

 每个时钟状态对应于一天中 1440 分钟中的一个。 从初始状态开始，反复添加$x$分钟生成确定性序列。 一旦某个状态重复，序列就会再次进入相同的循环，并且不会出现新的时间。 

该算法在此周期中访问每个不同状态一次。 循环中出现的每个回文时间都被插入到回文集中，并且回文集中会自动删除重复项。 由于循环包含维克多可以看到的所有时间，因此最终集合的大小正是他可见的不同回文数的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_palindrome_time(minutes):
    h = minutes // 60
    m = minutes % 60
    s = f"{h:02d}:{m:02d}"
    return s == s[::-1], s

t = int(input())

for _ in range(t):
    time_str, x = input().split()
    x = int(x)

    h = int(time_str[:2])
    m = int(time_str[3:])
    cur = h * 60 + m

    visited = set()
    palindromes = set()

    while cur not in visited:
        visited.add(cur)

        ok, s = is_palindrome_time(cur)
        if ok:
            palindromes.add(s)

        cur = (cur + x) % 1440

    print(len(palindromes))
```第一步将开始时间转换为表示自午夜以来的分钟数的单个整数。 在这种表示中，算术变得更加容易，因为推进时钟只是加法，然后对 1440 进行模运算。 

的`visited`set 存储分钟值而不是格式化字符串。 这唯一地标识每个时钟状态并允许在恒定时间内进行周期检测。 

回文测试是在格式化的`"HH:MM"`细绳。 由于所需的格式始终包含前导零，因此格式化`:02d`是必不可少的。 没有前导零，时间如`"05:50"`将被错误地表示并且回文检测将失败。 

一旦状态重复，循环就会停止。 在那一刻，整个未来序列也会重复，因此继续只会重新访问之前处理过的时间。
