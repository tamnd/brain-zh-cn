 ## 解决方案
 ## 问题理解

 我们得到一个数组并要求检查固定长度的每个连续段$k+1$。 对于从位置开始的每个这样的段$i$，我们通过乘以元素在概念上对其进行转换$j$（相对于段开始）$2^j$。 经过指数加权后，我们检查结果序列是否严格递增。 任务是计算有多少个起始位置产生有效段。 

直接读取隐藏了结构：我们没有对任何东西进行排序或重新排列，只是检查一个非常具体的不等式链是否适用于滑动窗口。 每个窗口都强加$k$比较，并且每次比较都会以两倍的比例混合相邻值。 

这些约束强制每个测试用例采用线性或近线性解决方案。 自从总共$n$所有测试用例最多是$2 \cdot 10^5$，任何解决方案$O(nk)$每个测试用例的工作立即太慢$k$也可以很大。 这促使我们采取一种方法，对比较进行预处理，以便可以签入每个窗口$O(1)$或摊销$O(1)$。 

当缩放后值相等或接近相等时，会出现微妙的边缘情况。 例如，如果$a = [2, 1]$和$k = 1$，我们比较$2 \cdot 2$和$1 \cdot 1$，获得平等。 要求是严格不等式，所以这个窗口一定不能计算在内。 使用 2 的浮点幂或错误地重新排列比较的幼稚实现可能会在计算时默默地将相等视为有效或错误处理整数溢出$2^j \cdot a_i$。 

另一个边缘情况是溢出或不必要的 2 的幂重新计算。 自从$2^k$如果简单地实现，可能会超出标准整数范围，任何依赖于每个窗口直接求幂的解决方案都会变得脆弱且低效。 

## 方法

 蛮力的想法很简单。 对于每个索引$i$，我们检查窗口$[i, i+k]$。 我们计算每个转换后的值$a_{i+j} \cdot 2^j$并验证所有相邻对都严格递增。 这需要花费$O(k)$每个窗口，导致$O(nk)$每个测试用例。 什么时候$n$很大并且$k$也很大，这会退化到大约$10^{10}$在最坏的情况下进行操作，这远远超出了限制。 

关键的观察是我们实际上不需要具体化缩放值。 窗口中两个相邻元素之间的条件是$$a_{i+j} \cdot 2^j < a_{i+j+1} \cdot 2^{j+1}.$$两边除以$2^j$（这是正数并且保留不平等方向），我们得到一个简化的形式：$$a_{i+j} < 2 \cdot a_{i+j+1}.$$这是核心简化：每个相邻比较仅取决于一对原始数组值，与窗口中的位置无关。 指数权重完全消失。 

因此，我们不是通过重新计算来检查整个窗口，而是预先计算一个布尔数组，指示每个相邻对是否满足$a_i < 2a_{i+1}$。 那么原来的问题就变成了计算有多少长度——$k$该布尔数组中的连续段都是完全正确的。 

这将问题简化为二进制数组上的滑动窗口。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nk)$|$O(1)$| 太慢了|
 | 最佳|$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 对于每一个相邻的对$(a_i, a_{i+1})$，计算是否$a_i < 2a_{i+1}$。 将结果存储在数组中`good[i]`。 

这将乘法指数约束转换为简单的局部条件。 
2. 观察有效的起始索引$i$因为原始问题对应于一个连续的段`good[i] ... good[i+k-1]`一切都是真的。 

这种重新表述将窗口长度从$k+1$元素到$k$布尔条件。 
3. 保持滑动窗口总和`good`。 初始化第一个的总和$k$的值`good`。 

如果总和等于$k$，满足该段中的所有条件。 
4. 将窗口滑动一步。 搬家时从$i$到$i+1$, 减去`good[i]`并添加`good[i+k]`。 

这使得每个窗口的检查时间保持恒定。 
5. 计算总和等于的每个窗口$k$，因为这意味着该段中的所有比较都是有效的。 

正确性依赖于以下事实：每个原始不等式链等价于取消 2 的幂后的独立相邻条件链。 每个窗口的有效性仅取决于其内部的所有局部约束是否成立。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        if k == 1:
            # window size 2, directly check condition
            ans = 0
            for i in range(n - 1):
                if a[i] < 2 * a[i + 1]:
                    ans += 1
            print(ans)
            continue

        good = [0] * (n - 1)
        for i in range(n - 1):
            if a[i] < 2 * a[i + 1]:
                good[i] = 1

        window_sum = sum(good[:k])
        ans = 1 if window_sum == k else 0

        for i in range(1, n - k):
            window_sum -= good[i - 1]
            window_sum += good[i + k - 1]
            if window_sum == k:
                ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```该代码首先将指数不等式链减少为存储在的相邻检查`good`。 特殊情况$k=1$为了清晰起见，直接处理，尽管一般的滑动窗口也可以统一工作。 滑动窗口总和跟踪完整的约束段是否成立，从而避免重新计算。 

一个常见的陷阱是差一索引：`good[i]`对应于之间的条件`a[i]`和`a[i+1]`，所以窗口开始于`i`用途`good[i]`通过`good[i+k-1]`。

 ## 边缘情况

 对于相等的相邻值，条件$a_i < 2a_{i+1}$当两者相等时总是失败，因为它变成$a_i < 2a_i$，这是真的，除非$a_i = 0$，但原始链中的严格不平等仍然通过变换正确传播。 该算法正确地标记了此类对，并防止包含它们的任何窗口被计算在内。 

对于非常大的值，计算永远不会形成$2^k \cdot a_i$，因此不存在溢出风险。 整个解决方案仅依赖于每次比较乘以 2 一次，这保持在 Python 和典型 64 位环境中的标准整数限制内。 

对于小$k$， 尤其$k=1$，该算法简化为直接邻接扫描。 该实现统一处理这个问题，但逻辑也明确地将其视为大小为 1 的退化滑动窗口`good`，确保窗口初始化时不出现差一错误。
