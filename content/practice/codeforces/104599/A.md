 ## 解决方案
 ## 问题理解

 我们得到了一组机器人朋友，每个朋友仅由一个代表其高度的整数值来描述。 鲍勃想通过垂直堆叠所有机器人来建造一个“巨型机器人”。 任务只是确定该堆栈的总高度，即所有单个机器人高度的总和。 

输入由一个整数 N 和后面的 N 个整数组成。 每个整数都直接影响最终结果，没有其他因素影响问题的结构。 没有顺序约束，值之间没有交互，也没有应用于各个高度的转换。 输出是一个等于总累积高度的整数。 

从约束来看，N 最多为 1000，每个高度最多为 1,000,000。 这意味着总和可以达到 10^9，这完全在标准 32 位有符号整数的范围内，尽管在通用解决方案中使用 64 位类型仍然是一个安全的习惯。 

故意将问题最小化，因此主要风险不是算法上的，而是与实现相关的。 一些微妙的边缘情况仍然存在。 

一种边缘情况是只有一个机器人时。 输入看起来像：```
1
42
```正确的输出是 42。这里的错误模式是假设至少两个值并从空或部分填充的结构错误地初始化总和的代码。 

另一个边缘情况是所有机器人都具有最大高度时：```
3
1000000 1000000 1000000
```正确的输出是 3000000。在具有严格溢出行为的语言中使用固定宽度 32 位整数的粗心实现可能会失败，尽管 Python 自然地避免了这个问题。 

第三种情况是所有值都为零时，这在约束中没有明确规定，但如果松散地解释，则在逻辑上是允许的。 总和仍应正确为零。 这可能会暴露逻辑，错误地使用非零默认值初始化累加器或在类似情况下跳过值`if h_i`。 

## 方法

 问题的结构表明元素之间不存在依赖关系，因此任何正确的解决方案都必须将所有值组合成一个聚合结果。 最直接的方法是迭代列表并累积运行总和。 

暴力思维可能会想象以不同的方式重新计算部分和，例如重复对前缀求和或从头开始重新计算总数以进行验证。 例如，可以计算每个前缀的总和并重复组合结果，甚至通过重复合并部分堆栈来模拟堆叠。 这最终仍然会减少对所有元素的求和，但会带来不必要的重复工作。 在最坏的情况下，从头开始重新计算每个元素的和会导致 O(N^2) 运算，对于 N ≤ 1000 来说这仍然很小，但它在结构上是浪费的，而且不是预期的方向。 

关键的观察结果是堆叠不会引入任何交互效应。 最终结构的高度在顺序和分组下是不变的，这意味着问题纯粹是加性的。 一旦认识到这一点，整个任务就会分解为单遍累积。

 ## 算法演练

 1. 读取整数 N，它决定后面有多少个高度。 这定义了我们必须聚合多少个值。 
2. 初始化变量`total`为零。 该变量表示迄今为止看到的所有机器人高度的运行总和。 
3. 逐一迭代 N 个输入值。 对于每个值`h`，将其添加到`total`。 此步骤直接反映了问题中描述的堆叠操作：每个机器人将其全部高度贡献给最终结构。 
4.处理完所有值后，输出`total`。 此时，每个机器人都已被包含一次，因此累加值就是巨型机器人的最终高度。 

### 为什么它有效

 该算法依赖于这样一个事实：最终结构是通过堆叠所有机器人而形成的，无需修改或重叠。 每个机器人对总高度的贡献都是独立的，并且没有交互改变其值。 由于加法是结合律和交换律，因此累加的顺序并不重要，并且每个有效的堆叠都对应于相同的和。 运行总计保持不变：处理完 k 个元素后，`total`等于前 k 个高度的总和。 当 k 达到 N 时，不变量保证`total`等于所有高度的总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input().strip())
    total = 0

    for _ in range(n):
        total += int(input().strip())

    print(total)

if __name__ == "__main__":
    main()
```该解决方案使用快速 I/O 读取输入，以避免开销，即使约束很小。 累加器`total`一次更新，这与概念上的堆叠过程完全一致。 每行都会被解析并立即合并，确保恒定的内存使用。 

一个微妙的实现细节是使用`strip()`从输入行读取整数时。 虽然在大多数情况下并不是绝对必要的，但它可以防止尾随空格的问题。 另一个细节是将累加器与输入解析分开，这可以避免意外重用循环变量或部分覆盖。

 ## 边缘情况

 对于单个机器人输入，例如`1`其次是`42`，循环只运行一次。 累加器从 0 开始，第一次迭代后变为 42，并直接打印。 这证实了初始化不依赖于具有多个元素。 

对于最大值，例如`1000000 1000000 1000000`，每次迭代都会增加一个很大的数字，但由于Python整数是无界的，因此不会发生溢出。 运行总数从 0 清晰地变化到 3,000,000，确认重复添加可以在限制范围内安全地扩展。 

对于全零输入，每次迭代都会使累加器保持不变。 不变式是`total`等于每一步处理元素的总和，并且最终输出在没有任何特殊情况下保持为零。
