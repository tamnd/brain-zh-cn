 ## 解决方案
 ## 问题理解

 我们对同一游戏进行了多次速通尝试，每次运行都会记录完成每个分段所需的时间。 每次运行都有相同数量的分割，因此输入可以看作是一个矩阵$N$行和$K$列，其中每行都是一个运行，每列对应一个固定的分割索引。 

对于每个查询，我们都会得到一个分割索引$s$，并且我们必须在所有运行中只查看该列。 来自那些$N$值，我们被要求找到两次运行之间的最大可能的改进，这意味着我们想要最大的正差异$t_j - t_i$在哪里$j > i$不是必需的，只是两者都来自不同的运行，并且我们按照给定的运行顺序比较时间。 

因此，每个查询都简化为：取矩阵的一列，并计算任何较晚值和任何较早值之间的最大差异，尊重运行顺序。 

关键的限制是$N, K \le 700$， 但$Q \le 10^5$。 这立即迫使我们预先计算每个分割的答案，因为重新计算每个查询会导致$O(N)$每个查询的工作量大约是$7 \times 10^7$最坏情况下的操作，在 Python 中是临界但有风险的。 更重要的是，重复扫描会造成浪费，因为同一个 split 会被查询多次。 

一个天真的想法可能是，对于每个查询，通过检查所有运行对来计算该列中的最佳对。 那将是$O(N^2)$每个查询，这是完全不可行的。 

一个微妙的点是每行内的运行严格增加（$t_i < t_{i+1}$在运行中），但这对跨运行没有帮助。 改进始终在一列中垂直定义。 

一个常见的错误是假设我们只需要相邻的运行。 例如，如果值为$1, 100, 2$，最好的改进是$100 - 1 = 99$，而不是相邻差异。 另一个错误是扫描方向错误，忽略了“最好的早期最小值”的重要性。 

边缘情况大多很小$N$， 例如$N=2$，其中答案只是两次运行之间的差异，以及值在运行中减少或增加的情况，这仍然可以产生不平凡的最大差异。 

## 方法

 暴力方法独立处理每个查询。 对于给定的分割$s$，我们提取它的列并尝试所有的运行对$i < j$, 计算$t_j - t_i$。 这是正确的，因为它明确地检查了每一个可能的改进。 然而，每次查询的成本$O(N^2)$，并与$Q = 10^5$，这大致变成$10^5 \cdot 700^2 \approx 5 \times 10^{10}$操作，远远超出了限制。 

关键的观察是，对于固定分割列，我们重复解决相同的经典问题：较大索引出现在较小索引之后的最大差异。 这可以通过在向下扫描运行时保持迄今为止看到的最小值来以线性时间计算。 

由于只有$K \le 700$列，我们可以预先计算每列的答案$O(NK)$，然后回答每个查询$O(1)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个查询的暴力破解 |$O(QN^2)$|$O(1)$| 太慢了|
 | 每列预计算 |$O(NK + Q)$|$O(K)$| 已接受 |

 ## 算法演练

 我们独立地预先计算每个分割的答案。 

1.对于每个分割索引$s$，我们向下扫描$N$按顺序运行。 

我们维护一个变量`min_value`，初始化为该分割的第一次运行的值。 

这是迄今为止在早期运行中看到的最短时间。 
2. 当我们进入下一次运行时$i$，我们计算潜在的改进：

 t[i][s] - \text{min_value}。 

我们更新了本次分组的运行最大答案。 
3.计算出分割的最佳改进后$s$，我们将其存储在一个数组中`best[s]`。 
4.对于每个查询，我们直接输出`best[s]`。 

我们维持前缀最小值的原因是任何以位置结束的有效改进$i$必须配对$t[i][s]$一些早期的运行，最好的早期运行正是迄今为止看到的最小值。 

### 为什么它有效

 在每个位置$i$，算法考虑所有有效对$(j, i)$和$j < i$通过仅跟踪所有早期值中的最小值来隐式地进行。 任何最优对结束于$i$必须使用最小的较早值，因为用较小的元素替换较早的元素只能改善或保留差异。 由于每个位置都被视为潜在端点，因此捕获了全局最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

N, K, Q = map(int, input().split())
t = [list(map(int, input().split())) for _ in range(N)]

best = [0] * K

for s in range(K):
    mn = t[0][s]
    mx_diff = 0
    for i in range(1, N):
        mx_diff = max(mx_diff, t[i][s] - mn)
        mn = min(mn, t[i][s])
    best[s] = mx_diff

out = []
for _ in range(Q):
    s = int(input()) - 1
    out.append(str(best[s]))

print("\n".join(out))
```解决方案首先阅读全文$N \times K$矩阵，以便每一列都可以独立处理。 对于每个分割索引，它运行一次线性扫描，保持迄今为止看到的最小值和发现的最佳改进。 这避免了任何嵌套对枚举。 

然后查询处理被简化为简单的数组查找。 唯一的微妙之处是将分割索引从基于 1 的索引转换为基于 0 的索引。

 ## 边缘情况

 关键的边缘情况是拆分中的所有值都相同。 该算法将最佳差值初始化为零，并且永远不会发现积极的改进，因为每次减法都会抵消。 对于输入：```
3 1 1
5
5
5
1
```扫描保持`mn = 5`自始至终，每个差值都为零，因此输出正确为 0。 

另一个边缘情况是严格递减值，其中最佳答案也应该为零，因为后来的值不会超过任何早期的最小值。 每一步都会更新最小前缀，确保不会记录任何正差异。 

最后的边缘情况是最佳对不相邻并且发生在多次更新最小值之后。 前缀最小机制确保即使稍后出现新的较小值，仍会为之前的位置考虑较早的较大间隙，因此不会错过最佳对。
