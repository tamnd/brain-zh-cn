 ## 解决方案
 ## 问题理解

 我们有一组放置在数轴上的机器人组。 每组都有一个位置，该位置上坐着许多机器人。 如果多个组共享相同的坐标，它们可以有效地合并为一个更大的组，因为它们的贡献是相同的并且可以聚合。 

合并后，我们在概念上在一条线上有了加权点。 我们可以选择一个整数位置$Y$这不等于任何现有的机器人位置。 一次$Y$是固定的，我们将所有机器人分成两侧：严格位于$Y$以及那些严格位于右侧的$Y$。 对于每一边，我们计算从$Y$考虑到多样性，该侧的每个机器人。 

我们关心的值是总左距离总和与总右距离总和之间的绝对差。 任务是选择一个有效的整数$Y$最小化该值。 

约束允许最多$10^5$组和坐标最多$10^9$，因此任何依赖于检查每个可能位置的方法$Y$立即是不可行的。 即使迭代所有坐标或它们之间的所有整数间隙也是不可接受的，除非每个步骤都是恒定时间并且步骤总数保持线性。 

因此，解决方案必须将问题减少到从结构导出的少量候选位置，而不是枚举所有整数。 

有两个重要的边缘情况打破了天真的推理。 首先，如果所有机器人都集中在一个坐标上，那么每个有效的$Y$距该点一定距离，并且对称性参数塌陷为常数表达式。 例如，输入：```
1
10 5
```任何$Y \neq 10$产生的差异等于$5 \cdot |Y-10|$，最小值出现在$Y=9$或者$Y=11$，给出答案$5$。 一种幼稚的方法，错误地允许$Y=10$将输出零，这是无效的，因为$Y$必须与所有不同$X_i$。 

其次，当群体分布稀疏时，最优$Y$通常位于两个连续占用的坐标之间，而不是它们之上。 仅评估现有坐标的方法将错过所有有效的最佳值。 

## 方法

 直接的方法是尝试每个有效的整数$Y$不等于任何$X_i$，并为每个候选者计算两个总和：到左侧和右侧的总加权距离。 每次计算都需要扫描所有组，因此总成本为$O(N^2)$在最坏的情况下，如果我们考虑密集的坐标范围。 即使限制候选人的协调范围仍然留下了$10^9$可能性，这是不可能的。 

表达式的结构是关键。 对于固定的$Y$，每个机器人在位置$x$贡献要么$A_i (Y-x)$如果$x < Y$， 或者$A_i (x-Y)$如果$x > Y$。 两边展开表明目标是由线性项构建的$Y$，按点位于左侧还是右侧进行分割$Y$。 这将创建一个分段线性函数，其中斜率仅在机器人位置发生变化。 

在任意两个连续的不同坐标之间，每侧的机器人集合不会改变，因此表达式变成了线性函数$Y$。 线性函数在其端点之一的线段上达到最小值。 既然我们被禁止选择$Y = X_i$，唯一可能的最佳位置紧邻现有坐标。 

这将问题简化为仅考虑排序的不同坐标之间的间隙。 对于每个差距，我们评估$Y = X_i + 1$或等效地严格介于$X_i$和$X_{i+1}$。 可以使用权重和加权位置的前缀和来有效地计算该值。

 ## 算法演练

 我们通过求和权重来压缩重复坐标，以便每个位置出现一次。 然后我们按坐标对结果对进行排序。 

1. 按位置对所有组进行排序，并通过求和权重来合并重复项。 这确保每个坐标只贡献一次，从而简化了前缀计算，因为我们不再需要单独推理相同的位置。 
2. 构建权重和加权位置的前缀和。 我们维持$W[i]$机器人总数达到指数$i$， 和$S[i]$作为总和$x \cdot a$直至索引$i$。 这些允许快速计算任何分割点的左右贡献。 
3. 对于连续坐标之间的每个间隙，考虑放置$Y$严格介于它们之间的任何地方。 成本表达式仅取决于间隙左侧和右侧有多少个机器人，可以从前缀数组中提取。 
4. 评估每个相邻对之间的边界处的成本。 在实践中，我们计算该值就好像$Y$的右边无限小$X_i$，对应于使用前缀最多$i$左侧为左侧，其余为右侧。 
5. 取所有此类分割位置的最小值。 

仅评估边界有效的原因是，在两个连续坐标之间的任何间隔内，左集和右集都保持不变，因此该函数是线性的$Y$并且不能有内部最小值。 

### 为什么它有效

 排序后任意有效位置$Y$将线划分为两组固定的索引：坐标小于$Y$和那些大于$Y$。 在连续不同坐标之间的任何间隔内，该分区不会改变。 目标函数变为线性函数$Y$在每个区间内，线性函数在端点处达到最小值。 由于端点与禁止坐标重合，因此最佳有效位置恰好是紧邻这些坐标的整数点，这对应于评估排序位置之间的每个分割。 这保证了在检查的候选者之外不存在更好的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = {}

    for _ in range(n):
        x, a = map(int, input().split())
        pts[x] = pts.get(x, 0) + a

    arr = sorted(pts.items())

    m = len(arr)
    x = [0] * m
    w = [0] * m

    for i, (xi, wi) in enumerate(arr):
        x[i] = xi
        w[i] = wi

    prefix_w = [0] * (m + 1)
    prefix_sw = [0] * (m + 1)

    for i in range(m):
        prefix_w[i + 1] = prefix_w[i] + w[i]
        prefix_sw[i + 1] = prefix_sw[i] + x[i] * w[i]

    total_w = prefix_w[m]
    total_sw = prefix_sw[m]

    ans = float('inf')

    for i in range(m - 1):
        left_w = prefix_w[i + 1]
        left_sw = prefix_sw[i + 1]

        right_w = total_w - left_w
        right_sw = total_sw - left_sw

        left_cost = left_w * x[i] - left_sw
        right_cost = right_sw - right_w * x[i]

        ans = min(ans, abs(left_cost - right_cost))

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先使用字典合并相同的坐标，以便每个位置贡献一个权重。 需要排序以确保前缀和对应于数轴上的连续间隔。 

前缀数组存储累积权重和累积加权位置。 这些允许在每次分割的恒定时间内计算左侧和右侧的贡献。 

对于之间的每个分割$i$和$i+1$，我们将分割视为$Y$位于右侧$x[i]$。 这个选择正确地模拟了任何有效的$Y$间隔中。 左成本计算为总距离$x[i]$对于左边的所有点，对于右边的点也是如此。 取绝对差值即可得出该区域的目标值。

 ## 边缘情况

 对于单个坐标输入，例如`1 10`，该算法产生一个合并点。 除了该坐标周围之外，没有有效的分割边界，因此唯一的候选者贡献的成本与距所选边界的距离成正比。 正确评估单个分割会返回最小非零值，与以下约束相匹配$Y$不能等于占用的坐标。 

对于紧密聚集的坐标，例如`1 1, 2 1, 3 1`，前缀结构确保连续点之间的每个分割都经过测试。 正确的最小值出现在中心间隙处，并且算法捕获了它，因为每个区间边界都只被考虑一次，即使对称性是完美的，也能保持正确性。
