 ## 解决方案
 ## 问题理解

 每个测试用例都会给出两个数字列表：模型产生的预期输出和实际输出。 对于每对$(e_i, a_i)$，我们通过检查绝对差是否来决定预测是否可接受$|a_i - e_i|$至多是$K$。 如果是，我们认为这种情况是正确的。 

任务是计算所有案例中正确案例的比例$N$例并将其输出为百分比，四舍五入到最接近的整数。 

输入大小最多允许$N = 10^4$每次测试，值高达$10^9$，因此唯一有意义的工作是对数据进行单次传递。 任何尝试对每个值进行预处理或排序的解决方案都是不必要的。 线性扫描就足够并且是最佳的。 

一个常见的失败案例是不正确的舍入。 例如，如果 3 个案例中有 1 个是正确的，则原始百分比为$33.333\ldots$，正确的输出是$33$， 不是$34$。 另一个微妙的情况是整数除法截断：计算$(\text{correct} \cdot 100) / N$仅当随后显式处理舍入时，使用整数除法才可以。 

## 方法

 蛮力方法只是迭代所有对，检查条件$|a_i - e_i| \le K$，计算有多少人满足它，然后计算百分比。 这在结构上已经是最佳的，因为每对都必须至少检查一次。 

关键的观察结果是，配对之间不存在相互依赖性。 每次检查都是独立的，因此解决方案只是计算流中满足要求的元素，并在最后将该计数转换为百分比。 不需要排序、前缀结构或转换。 

唯一重要的部分是正确舍入。 标准技巧是计算$$\text{ans} = \frac{100 \cdot \text{correct} + \frac{N}{2}}{N}$$它使用整数算术实现四舍五入到最接近的整数。

 | ---| ---| ---| ---|
 | 暴力扫描 |$O(N)$|$O(1)$| 已接受 |
 | 具有正确舍入的相同扫描 |$O(N)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 阅读$N$和$K$。 这些定义了比较次数和正确性的容差阈值。 
2. 初始化计数器$\text{correct} = 0$累积有多少对满足条件。 
3. 对于每对$(e_i, a_i)$, 计算$|a_i - e_i|$并将其与$K$。 如果该值最多为$K$, 增量$\text{correct}$1. 这直接实现了有效预测的定义。 
4. 处理完所有对后，将百分比计算为$\frac{100 \cdot \text{correct}}{N}$，但通过添加四舍五入到最接近的整数$\frac{N}{2}$划分之前。 
5. 输出结果整数。 

### 为什么它有效

 每对都独立地对正确性计数做出贡献，因此总准确度完全通过对每个条件的指标变量求和来确定$|a_i - e_i| \le K$。 最终值是该总和的线性变换。 由于舍入仅在最后应用一次，因此中间精度损失不会影响正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    correct = 0

    for _ in range(n):
        e, a = map(int, input().split())
        if abs(e - a) <= k:
            correct += 1

    # rounded percentage
    ans = (correct * 100 + n // 2) // n
    print(ans)

if __name__ == "__main__":
    solve()
```该实现线性读取输入并以每对恒定时间更新计数器。 绝对差异检查直接强制执行公差条件。 舍入公式可确保正确的最接近整数百分比，无需浮点运算，从而避免精度问题。
