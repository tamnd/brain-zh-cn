 ## 解决方案
 ## 问题理解

 我们得到了一组整数，并且可以将它们任意重新排序为一个序列。 目标是决定我们是否可以排列它们，使每个相邻对都满足模关系：每个连续对的总和（以 M 为模）必须等于固定目标值 K。 

换句话说，如果我们将数字放入序列 P 中，则对于每个相邻对 P[i], P[i+1]，条件

 (P[i] + P[i+1]) mod M = K

 对于所有有效的 i 必须同时保持。 如果存在这样的排序，我们必须输出一个有效的排列； 否则，我们输出这是不可能的。 

约束 n 高达 2 × 10^5 迫使我们远离任何二次方或涉及所有对的显式图构造。 任何尝试检查所有排列的解决方案都立即不可行，因为 n! 太大了，即使在尝试交换后天真地检查邻接约束仍然会太慢。 

一个微妙的点是，条件仅取决于模 M 的值，而不取决于索引或绝对顺序。 这创建了一个隐藏的配对结构：每个数字实际上都需要一个互补的伙伴来完成所需的模 M 之和。 

有两种重要的边缘情况常常打破朴素的推理。 

如果所有值都相同，例如 A = [x, x, x, x]，则条件变为 (2x mod M) 必须等于 K。如果失败，则即使所有元素都相同，也无法进行任何排列，这可能会误导贪婪的实现，使贪婪的实现假设相同的值始终是安全的。 

另一种情况是当 n = 1 时。不存在相邻对，因此条件满足，并且无论 K 是多少，任何单个元素排列都是有效的。 

最后，重复很重要。 如果我们尝试贪婪地匹配值而不计算频率，我们可能会错误地重用元素或错过所需的补集已用完的情况。 

## 方法

 暴力破解的想法很简单：生成数组的所有排列并测试每个排序是否满足模邻接条件。 这是正确的，因为它直接遵循问题的定义。 然而，排列的数量是 n！，对于 n = 2 × 10^5，这甚至无法通过计算来概念化。 即使 n = 10，这也会成为临界值，超过这个值就会爆炸。 

我们需要一种方法来完全避免搜索排列。 关键的观察是关注单个相邻对施加的约束。 如果出现两个连续的元素x和y，它们必须满足x + y == K (mod M)。 这可以重写为 y == K − x (mod M)。 这意味着序列中的每个元素都必须与模 M 下唯一确定的补码配对。 

这将问题转化为多重集上的配对问题：每个值 x 必须与 K − x mod M 匹配。一旦形成对，按顺序排列它们就变得微不足道，因为每个对都是局部一致的。 

唯一剩下的结构问题是配对必须在全局范围内保持一致，这意味着每个元素必须精确匹配一次。 这将问题简化为检查该隐式配对系统中是否存在完美匹配，这可以通过频率计数来解决。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 频率配对 | O(n log n) 或 O(n) | O(n) | 已接受 |

 ## 算法演练

 我们针对数组中的所有值构建频率图。 然后我们尝试将每个值 x 与其所需的补码 y = (K − x mod M + M) mod M 配对。

1. 计算 A 中所有值的频率。这为我们提供了多重集表示，以便我们可以安全地使用元素。 
2. 迭代频率图中的每个不同值 x。 对于每个 x，计算其所需的伙伴 y，使得 x + y == K (mod M)。 模块化调整确保 y 始终在 [0, M) 内。 
3. 如果 x 已被之前的配对完全使用，则跳过它。 这可以防止双重处理对。 
4. 如果x等于y，意味着它是自补的，那么它的频率一定是偶数。 否则，一次出现将保持不匹配，从而不可能进行完整的排列。 
5. 如果 x 与 y 不同，那么我们必须将所有出现的 x 与 y 匹配。 这需要 freq[x] == freq[y]。 如果不相等，我们就无法将所有内容一致地配对。 
6. 验证后，我们通过重复附加 x 和 y freq[x] 次（对于 x ≠ y）或在自补情况下配对相同的值来构造输出。 

除了尊重配对之外，构造顺序并不重要，因为任何有效对序列都可以连接，并且仍然满足每个对块内的邻接约束。 

### 为什么它有效

 关键的不变量是每个值都必须恰好与一个满足模和约束的互补值配对。 由于每个元素在每一侧都只参与一个邻接关系（端点除外，它仍然需要配对一致性），因此整个序列分解为不相交的有效对。 如果任何值不能与其补码以相同的频率完美匹配，则至少有一个邻接约束必须失败，从而无法进行有效的排列。 相反，如果所有频率都可以以这种对称方式匹配，我们总是可以连续排列这些频率对以形成有效的序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, M, K = map(int, input().split())
    A = list(map(int, input().split()))
    
    from collections import Counter
    freq = Counter(A)
    
    used = set()
    res = []
    
    for x in list(freq.keys()):
        if freq[x] == 0:
            continue
        if x in used:
            continue
        
        y = (K - x) % M
        
        if y not in freq:
            print("NO")
            return
        
        if x == y:
            if freq[x] % 2 != 0:
                print("NO")
                return
            res.extend([x] * freq[x])
            used.add(x)
        else:
            if freq[x] != freq[y]:
                print("NO")
                return
            used.add(x)
            used.add(y)
            for _ in range(freq[x]):
                res.append(x)
                res.append(y)
    
    print("YES")
    print(*res)

if __name__ == "__main__":
    solve()
```该实现是配对逻辑的直接翻译。 计数器存储多重性，因此我们永远不会丢失重复项。 使用的集合确保每个等价类值仅处理一次，从而防止 x 和 y 之间意外的双重配对。 

构造步骤任意交错每个有效的对类型； 有效对的任何排序都是可接受的，因为约束仅局部应用于相邻元素。 

一个常见的微妙错误是在计算 y 时忘记模归一化，这会产生负值。 表达式 (K - x) % M 确保正确性。

 ## 边缘情况

 关键的边缘情况是当一个值在模数下自补时。 例如，当 M = 10 且 K = 4 时，值 2 满足 2 + 2 ≡ 4 mod 10。如果它出现奇数次，例如三个副本，则任何贪婪配对都会留下一个未配对的元素。 该算法在构建任何内容之前正确检查奇偶校验，从而防止部分但无效的排列。 

当多个值映射到相同的补体结构但频率不一致时，会出现另一种边缘情况。 例如，如果 x 映射到 y 但 freq[x] > freq[y]，则贪婪构造可能仍会生成对，直到耗尽并稍后默默失败。 频率之间的明确相等性检查通过在输出构造之前验证可行性来防止这种漂移。 

最后一个微妙的情况是 n = 1。由于没有邻接约束，算法永远不会以有问题的方式进入配对逻辑。 频率图包含单个元素，并且它被视为自洽，立即产生有效的输出。
