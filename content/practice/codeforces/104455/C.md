 ## 解决方案
 ## 问题理解

 给定三个长度相等的数组，每个位置包含一个正整数。 从这些数组中，我们并不是以受约束的顺序或结构来选择元素，我们只是通过从每个数组中选取一个索引来形成独立的三元组。 对于每种指数选择$i, j, k$，我们计算产品$a_i \cdot b_j \cdot c_k$，我们想要计算有多少个这样的三元组恰好产生目标值$m$。 

因此，该任务纯粹是值的组合：每个数组中的每个出现都独立参与，并且除了重数之外，相同的值是无法区分的。 

关键的限制是$n$可以大到$5 \cdot 10^5$。 所有三元组的直接枚举将考虑$n^3$组合，最坏的情况是$1.25 \cdot 10^{17}$运营。 即使进行重度修剪，这种规模在两秒钟内也是完全不可行的。 这立即迫使我们将问题压缩到频率空间而不是索引空间。 

另一个重要的约束是每个数组元素最多$m$， 和$m \le 10^9$。 这很重要，因为整除结构变得至关重要：如果一个值不能整除$m$，它永远无法构成有效的三元组。 

一些微妙的边缘情况自然会出现。 

如果$m = 1$，那么每个有效的三元组必须完全由 1 组成。 例如，如果所有数组都是$[1, 2]$，那么只有三个选秀权都为 1 的位置才有贡献，其他一切都无关紧要。 

如果数组包含不能整除的值$m$， 例如$a = [2, 3]$和$m = 6$，那么只有除数$m$问题，非约数可以完全忽略。 

当出现更微妙的情况时$m$具有重复因子结构。 例如，$m = 18$。 三倍喜欢$(2, 3, 3)$,$(3, 3, 2)$，并且排列都会起作用，并且计数必须尊重数组之间的多重性而不是唯一值。 

朴素推理的主要失败模式是将其视为对值的单个搜索，而没有正确考虑每个数组中的频率重数。 

## 方法

 思考该问题的一种直接方法是迭代所有索引三元组，计算乘积，并检查它是否等于$m$。 这是正确的，因为它完全符合问题的定义。 但是，它需要三个嵌套循环$n$, 生产$O(n^3)$运营。 和$n = 5 \cdot 10^5$， 甚至$n^2$已经太大了，所以$n^3$是绝对不可能的。 

关键的观察结果是产品状况在三个阵列中完全分离。 我们不再考虑指数，而是转向计算值的频率。 如果我们知道每个值在每个数组中出现多少次，那么每个值的选择都会产生乘法贡献：$x$出现$f_a[x]$次在$a$,$f_b[y]$次在$b$， 和$f_c[z]$次在$c$，那么产生的索引三元组的数量$(x, y, z)$是$f_a[x] \cdot f_b[y] \cdot f_c[z]$。 

所以问题归结为计算所有值三元组$(x, y, z)$这样$x \cdot y \cdot z = m$，按频率加权。 

这将问题转化为除数结构$m$。 我们只考虑数组中的除数，而不是迭代数组中的所有值$m$，因为有效三元组中的任何因数都必须整除$m$。 的约数个数$m \le 10^9$很小（最坏情况下最多几千），这使得枚举变得可行。 

因此，最佳策略是：计算所有三个数组的频率图，枚举除数$x$和$y$的$m$，推导出$z = m / (x \cdot y)$，并验证它是积分并且存在于第三频率图中。 

这减少了搜索空间$n^3$索引组合大致$d(m)^2$值组合，其中$d(m)$是的约数$m$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^3)$|$O(1)$| 太慢了 |
 | 频率+除数枚举|$O(n + d(m)^2)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 统计数组中所有值的出现频率$a$,$b$， 和$c$。 这使我们能够用基于多重性的计数替换基于索引的计数。 
2. 计算所有除数$m$。 每个除数代表一个可能的值，可以出现在有效三元组的任何位置。 这一步至关重要，因为只有$m$可以参与产品等于$m$。 
3. 迭代每个除数$x$的$m$。 对待$x$作为从数组中选择的值$a$。 我们将答案乘以选择贡献价值的指数的方法数量$x$，这是它的频率$a$。 
4. 对于每一个这样的$x$，迭代每个除数$y$的$m$。 对待$y$作为数组中的值$b$。 我们乘以它的频率$b$。 
5. 计算$z = m / (x \cdot y)$。 如果$m$不能被整除$x \cdot y$，跳过这一对，因为不存在有效的第三个值。 
6. 检查是否$z$存在于数组中$c$使用频率图。 如果有，请添加$f_a[x] \cdot f_b[y] \cdot f_c[z]$到答案。 

### 为什么它有效

 每个有效的索引三元组对应于值的三元组$(x, y, z)$这样$x \cdot y \cdot z = m$。 该算法将每个这样的值三元组枚举一次，因为$x$和$y$范围超过所有因数$m$， 和$z$有效时唯一确定。 每个贡献均按来自三个数组的独立重数进行加权，因此不会遗漏或重复计算有效的索引组合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import Counter
import math

n, m = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))
c = list(map(int, input().split()))

fa = Counter(a)
fb = Counter(b)
fc = Counter(c)

divs = []
for i in range(1, int(math.isqrt(m)) + 1):
    if m % i == 0:
        divs.append(i)
        if i * i != m:
            divs.append(m // i)

ans = 0

for x in divs:
    if x not in fa:
        continue
    for y in divs:
        if y not in fb:
            continue
        prod = x * y
        if m % prod != 0:
            continue
        z = m // prod
        if z in fc:
            ans += fa[x] * fb[y] * fc[z]

print(ans)
```频率图完全取代了索引跟踪，确保我们正确地考虑重复值。 除数列表一次构建，避免了重复的因式分解工作。 嵌套除数循环是安全的，因为即使在最坏的情况下，除数计数也很小。 

一个微妙的实现细节正在检查`m % prod != 0`计算前`z`，这可以防止无效的整数除法情况并避免不必要的字典查找。

 ## 边缘情况

 一种边缘情况是当$m = 1$。 在这种情况下，每个有效的三元组必须仅使用值 1。该算法自然地处理此问题，因为除数列表仅包含 1。循环减少为单个检查，其中$x = y = z = 1$，结果就变成了$f_a[1] \cdot f_b[1] \cdot f_c[1]$，这是完全正确的。 

另一种情况是当数组包含许多不能整除的值时$m$。 这些值永远不会出现在除数列表中，因此它们会被基于频率的循环自动忽略。 例如，如果$m = 10$并且数组包含许多 3，这些条目永远不会参与，因为 3 永远不会被视为候选除数。 

最后一个微妙的情况是$x \cdot y$超过$m$。 支票`m % prod != 0`确保我们永远不会尝试无效的第三个组件。 例如，如果$m = 12$，选择$x = 4$和$y = 4$产生乘积 16，该乘积在对第三个映射进行任何查找之前立即被丢弃。
