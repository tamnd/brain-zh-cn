 ## 解决方案
 ## 问题理解

 我们得到了一组卡片，每张卡片都标有从 1 到 n 的数字。 对于每个数字 i，我们都有该类型的 a_i 卡。 我们也有 k 个硬币，每个硬币允许我们购买任意类型的新卡，因此我们可以任意增加任意数量的数量，只要我们总共购买的数量不超过 k 即可。 购买后，我们将所有卡片排成一行，并统计有多少个长度为 n 的连续子数组是 [1, 2, ..., n] 的排列。 我们的任务是最大化该计数。 

输入由多个测试用例组成。 每个测试用例指定 n、k 以及初始计数 a_1 到 a_n。 每个测试用例的输出是一个整数，即完全排列的 n 长度子数组的最大数量。 

约束条件很大：n可以达到2×10^5，k可以达到10^12，a_i也可以达到10^12。 这排除了任何尝试模拟所有子数组或重新排列的方法。 我们必须依赖计数和分配逻辑，而不是显式生成序列。 

一个重要的边缘情况是 n = 1 时，因为每张卡都是 [1] 的排列。 另一种情况发生在 k 相对于 a_i 极大时； 我们也许能够购买足够的卡片来使每个 a_i 相等，从而最大化排列的数量。 粗心的实现可能会尝试构造一个实际的数组，但由于内存限制或溢出而失败。 

## 方法

 暴力方法会尝试在购买最多 k 张新卡后生成所有卡牌序列，然后滑动大小为 n 的窗口并检查每个窗口是否是排列。 这在原则上是正确的，但很快就变得不可行。 即使 n = 10^5，也有 n！ 长度为 n 的排列，当 a_i 和 k 达到 10^12 时，不可能生成长度为 sum(a_i) + k 的数组。 操作数呈指数级增长，内存使用量呈天文数字。 

关键的见解是认识到问题可以简化为在 n 种类型之间均匀分配卡片。 如果我们想象以重复序列形成排列，则 n 长度排列子数组的最大数量由购买额外卡片后任何类型的最小计数决定。 具体来说，如果购买后我们能够保证所有类型至少出现m次，那么我们就可以形成m个完整的排列块。 剩下的卡片允许我们以交错的方式形成额外的排列，但主导因素始终是数量最少的类型。 

这将问题简化为二分搜索：我们搜索最大的整数 m，以便我们可以使用最多 k 个硬币将每个 a_i 增加到至少 m。 对于每个候选 m，我们将所需的额外卡片总数计算为 sum(max(0, m - a_i) for i = 1..n)。 如果该总和 <= k，则 m 是可以实现的。 二分查找有效地找到最大的可行 m。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n * (总和(a_i) + k)) | O(总和(a_i) + k) | 太慢了 |
 | 二分查找+计数| O(n log(max(a_i) + k)) | O(n log(max(a_i) + k)) | O(n) | 已接受 |

 ## 算法演练

1.读取测试用例的数量。 独立循环每个测试用例。 
2. 对于当前测试用例，读取 n、k 和计数数组 a。 
3. 初始化二分查找范围。 最小可能的排列是 0，如果我们花费所有 k 个硬币来均衡最小类型：max(a) + k，则最大值是最大可能的计数。 
4. 执行二分查找。 对于每个候选者 m，计算将每个 a_i 提高到至少 m 所需的硬币总和。 对于a_i已经>= m，不需要硬币； 否则，我们需要 m - a_i 个硬币。 
5. 如果所需的总币数<= k，则候选m是可行的。 更新搜索以尝试更大的 m。 否则，减小 m。 
6. 二分查找后，最大可行的m就是我们能保证的最大完整排列数。 
7. 输出该数字。 

为什么它有效：二分查找之所以有效，是因为函数“is m achievable”是单调的。 如果 m 是可以实现的，那么任何更小的 m 也是可以实现的。 如果 m 无法实现，那么任何更大的 m 也是不可能的。 不变的是，最后我们已经确定了最大的 m，这样我们就可以保证 [1, 2, ..., n] 的至少 m 个完整排列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def max_permutations(n, k, a):
    low, high = 0, max(a) + k
    while low < high:
        mid = (low + high + 1) // 2
        required = sum(max(0, mid - x) for x in a)
        if required <= k:
            low = mid
        else:
            high = mid - 1
    return low

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    print(max_permutations(n, k, a))
```该解决方案首先根据当前最大的牌数加上 k 个硬币来设置二分搜索范围。 对于每个候选者 m，它计算所需的硬币并将其与 k 进行比较。 的选择`(low + high + 1) // 2`确保搜索在最大可行 m 上正确终止。 这`max(0, mid - x)`确保我们只计算 a_i 低于中值的硬币，避免负面贡献。

 ## 边缘情况

 当n=1时，任意数量的硬币都可以直接增加单一类型的计数，因此输出为a_1 + k。 二分搜索可以正确处理这个问题，因为 required = max(0, mid - a_1)。 对于与 a_i 相比非常大的 k，二分搜索确定在最佳分配硬币后可以创建多少个完整排列，始终由最小调整类型控制。 当 a_i 已经很大并且 k 很小时，算法会正确计算出不可能有超出最小现有计数的额外排列。
