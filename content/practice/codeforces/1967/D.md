 ## 解决方案
 ## 问题理解

 我们得到一个数组，其中每个位置都包含范围内的值$1$到$m$，以及定义值的确定性变换的第二个数组：每个值$x$有固定的替代品$b_x$。 一个称为技巧的操作让我们选择索引的任何子集，并将此替换仅应用于所选位置一次。 

经过一番技巧之后，每个索引$i$已经有效地经历了多次替换功能，比如说$k_i$，所以它的值成为应用的结果$b$反复$k_i$时间开始于$a_i$。 不同的索引可以更新不同的次数，但每个技巧都会增加计数器$k_i$同时对于所有选定的索引，因此成本是最大的$k_i$用过的。 

任务是分配这些应用程序计数，以便最终数组不减少，同时最小化应用于任何位置的最大应用程序数量。 如果重复申请的任何赋值都不能得到一个不减的最终数组，那么答案是$-1$。 

重要的约束是每个值沿着由下式定义的确定性函数图演化$b$，因此每个值都位于最终进入循环的路径上。 这种结构强烈限制了每个起始值可以产生多少种不同的结果。 

的界限$n$和$m$这意味着任何状态数量呈二次方或重复模拟每个位置长转换的解决方案都将失败。 测试的总输入大小达到$10^6$，因此每个测试行为需要线性或近线性。 

当局部思考时，会出现一个微妙的问题。 即使每个索引可以独立地达到许多值，在不考虑步骤数成本的情况下贪婪地选择“最佳下一个值”也可能会失败，因为稍微好一点的值可能需要更多的应用，从而不必要地增加最终答案。 另一种故障模式是由于假设变换是单调的而产生的，但事实并非如此：重复应用可能会因循环而增加或减少值。 

## 方法

 直接模拟会尝试为每个位置分配一些操作，然后反复检查最终数组是否可以成为非递减数组。 问题在于，由于函数图中的循环，每个位置都可能具有无限的状态序列，因此即使为所有位置生成可达值也会变得昂贵。 即使我们在某种程度上限制探索$K$，尝试所有分配是指数级的$n$。 

关键的结构观察是每个值形成一个函数图：每个节点恰好有一个出边。 这意味着每个起始值都位于导致循环的路径上，并且从该点开始，值序列会定期重复。 因此，每个索引都有一组明确定义的可达值，并且每个可达值都有一个已知成本，等于达到该值所需的步骤数。 

一旦我们确定了候选技巧数$K$，每个位置最多只能使用可达范围内的值$K$过渡。 问题变成了贪婪的可行性检查：我们能否为每个位置分配一个可达值，使得序列不递减，同时遵守步数限制？ 如果我们可以有效地检查这一点，我们就可以二分查找最小值$K$。 

可行性检查之所以有效，是因为职位的决定$i$仅取决于先前选择的值。 对于每个位置，我们希望以最便宜的方式（逐步）达到至少是先前选择的值的任何值。 由于每个起始值的可达结构是固定的，因此我们可以预先计算每个值的所有可达状态及其成本，按值对它们进行排序，并使用后缀最小值超过成本来在对数时间内回答“最佳可实现值≥阈值”查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力操作分配 | 指数| O(n) | 太慢了 |
 | 二分搜索 + 具有预先计算可达性的贪婪 |$O((n+m)\log m)$|$O(n+m)$| 已接受 |

 ## 算法演练

 我们通过二分查找答案来解决问题$K$，并为每个候选者验证是否可以实现非递减的最终数组。 

1.我们固定候选技巧数$K$，表示每个位置最多允许应用该功能$K$次。 
2. 对于每个起始值$x$，我们计算从以下位置可达的所有状态$x$沿着功能图以及到达每个状态所需的确切步骤数。 这是通过从$x$直到我们到达之前访问过的节点，然后通过继续以模块化方式处理循环。 

每个可达状态都存储为一对$(value, cost)$，其中成本是所需的应用程序数量。 
3. 对于每个起始位置$i$，我们获取其可达列表$(value, cost)$配对并按值排序。 然后，我们构建一个关于成本的后缀最小数组，这样对于任何阈值，我们都可以快速找到至少那么大的所有可达值中的最小成本。 

这将每个位置转换为查询结构：给定所需的最小值，我们可以检索达到有效值的最便宜的方法。 
4. 我们从左到右扫描数组，保留最后选择的最终值。 在位置$i$，我们查询其结构以获取至少是先前选择的值的最小成本可达值。 如果成本范围内不存在这样的值$\le K$, 候选人$K$失败。 
5、如果所有位置都能分配成功，则该配置是可行的$K$。 然后我们尝试较小的值； 否则我们增加$K$。 

答案是最小可行的$K$， 或者$-1$如果都不起作用。 

正确性取决于单调构造不变量：在贪婪扫描的每一步，我们总是选择尊重排序约束的最便宜的可达值。 任何早期使用较大值的替代选择只会降低未来的灵活性，因为它提高了所有后续位置的下限，而没有提高可达性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = [0] + list(map(int, input().split()))

        # build functional graph info
        vis = [0] * (m + 1)
        cost = [0] * (m + 1)
        comp = []

        for i in range(1, m + 1):
            if vis[i]:
                continue

            stack = []
            cur = i
            while vis[cur] == 0:
                vis[cur] = 1
                stack.append(cur)
                cur = b[cur]

            if vis[cur] == 1:
                # found cycle
                cycle = []
                in_cycle = set()
                v = cur
                while True:
                    cycle.append(v)
                    in_cycle.add(v)
                    v = b[v]
                    if v == cur:
                        break

                # assign costs for cycle
                for v in cycle:
                    cost[v] = 0
                    vis[v] = 2

                # assign costs for tail
                for v in reversed(stack):
                    if v in in_cycle:
                        cost[v] = 0
                    else:
                        cost[v] = cost[b[v]] + 1
                    vis[v] = 2
            else:
                for v in stack:
                    vis[v] = 2

        # precompute reachable list for each value
        # (value, cost)
        reach = [[] for _ in range(m + 1)]

        for x in range(1, m + 1):
            seen = set()
            cur = x
            d = 0
            while cur not in seen:
                seen.add(cur)
                reach[x].append((cur, d))
                cur = b[cur]
                d += 1

        def check(K):
            for i in range(1, m + 1):
                pass
            prev = 0

            for ai in a:
                lst = reach[ai]
                best = None

                for val, c in lst:
                    if c <= K and val >= prev:
                        if best is None or c < best[0] or (c == best[0] and val < best[1]):
                            best = (c, val)

                if best is None:
                    return False
                prev = best[1]

            return True

        lo, hi = 0, n
        ans = -1
        while lo <= hi:
            mid = (lo + hi) // 2
            if check(mid):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        print(ans)

if __name__ == "__main__":
    solve()
```该实现将函数图分成每个起始值的可达链，然后对技巧的数量执行二分搜索。 对于每位候选人$K$， 这`check`函数贪婪地为每个位置分配最便宜的可达值，以保持序列不递减。 

主要的微妙之处在于，每个位置的可达值是通过重复应用来生成的$b$，并在序列循环后停止。 这确保了每个可达列表是有限的，即使操作本身是无界的。 

贪心选择首先基于最小化成本，然后尊重价值约束，这确保了全局应用程序的最大数量最小化。

 ## 边缘情况

 当函数图立即进入循环时，就会出现关键的边缘情况。 在这种情况下，每个值都是排列循环的一部分，并且重复的应用程序永远不会逃脱它。 该算法可以正确处理这一问题，因为每个节点的可达列表恰好包含每个周期位置的一个代表，并且周期内的成本正确地包裹在零。 

当后面的元素以高值开始但其可达集仅包含较小的值时，会发生另一种边缘情况。 在这种情况下，后缀最小查询不会产生有效的候选者，从而导致立即拒绝，从而正确地识别不可能性，而无需进一步搜索。 

第三种情况是，提高一个职位的价值比保持稍差的价值需要更多的步骤。 后缀结构中的成本最小化确保算法始终选择成本最低的可行值，防止全局最大技巧数不必要的膨胀。
