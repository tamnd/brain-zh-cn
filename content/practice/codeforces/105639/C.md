 ## 解决方案
 ## 问题理解

 我们得到了一个由单向转换连接的交叉路口的有向网络。 每个转变都有两个属性：传播时间和热变化。 如果过渡代表室外街道，它会减少当前的热量； 如果它位于建筑物走廊内，则会增加热量。 无论解释如何，每个动作都会确定性地改变运行的“温度状态”。 

旅行者从十字路口 1 出发，热量恰好为 0，并希望到达十字路口\(n\)。 仅当每时每刻热值保持在以下范围内时，行程才有效：\(-30\)到\(+30\)。 如果某个举动会将热量推到该范围之外，则禁止该举动。 

目标是计算从节点 1 到节点的所有有效路线中的最小总行程时间\(n\)，或报告不可能。 

约束结构至关重要。 最多有\(10^5\)节点和\(10^5\)跨所有测试用例的边，并且每条边最多可以改变 30 个热量。热量维度很小且有界，因此任何将其视为大小为完整附加图形维度的解决方案\(61n\)如果小心处理的话，在记忆和时间上已经可以接受。 然而，在没有最短路径结构的路径上的朴素动态规划将由于循环和重复状态而爆炸。 

仅跟踪每个节点的最佳时间的幼稚方法是不正确的，因为以不同的热值到达同一节点会导致不同的未来可能性。 例如到达节点\(v\)热量为 30 时可能会阻止所有传出的负边缘，而热量为 -30 时可能会在以后提供更多灵活性。 

小循环图中出现了微妙的失败案例。 考虑：```
1 -> 2 (dt = +30)
2 -> 1 (dt = -30)
```从 1 开始，热度为 0，我们可以在状态 (1,0) → (2,30) → (1,0) 之间循环，但是任何将节点 1 视为“已最佳访问”的尝试都会破坏正确性，因为使用不同的热度状态重新访问很重要。 

另一种边缘情况是当路径暂时超出边界时，即使净效应是安全的。 例如：```
1 -> 2 (dt = +30)
2 -> 3 (dt = -30)
3 -> 4 (dt = +30)
```即使最终的热量仍然有效，中间步骤也必须遵守边界，因此路径可行性在每个边缘都取决于状态。 

## 方法

 蛮力思想是考虑从 1 到 1 的所有可能路径\(n\)，跟踪每条路径上的热量。 每个步骤都会更新热量并检查有效性。 这在原则上是正确的，因为它严格执行约束，但在具有循环的一般图中，路径数量呈指数增长。 即使限制为简单的路径也无济于事，因为除非仔细限制，否则热状态可以循环重复，从而产生无限多个有效变化。 

关键的结构见解是唯一有意义的状态是一对 \((node, heat)\)，并且 heat 被限制为 61 个可能的值。 这将问题转换为分层图上的最短路径问题，最多\(61n\)州。 每个原始边都会引起层之间的转换，并且所有边权重都是非负的（时间始终为正），因此直接应用 Dijkstra 算法。 

对路径的暴力破解会失败，因为它会多次重新计算相同的\((node, heat)\)状态。 分层状态公式将所有等效历史折叠成扩展图中的单个节点，将指数探索转变为多项式最短路径计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 暴力破解路径 | 指数| O(1) 额外 | 太慢了|
 | 国家扩张的 Dijkstra | O(m·61 log (n·61)) | O(n·61 + m·61) | 已接受 |

 ## 算法演练

 我们对待每对 \((v, h)\) 其中\(v\)是一个节点并且\(h \in [-30, 30]\)是作为图中不同状态的有效热值。 

1.初始化距离表`dist[v][h]`所有节点和热值均为无穷大。 该表代表到达节点的最佳已知时间\(v\)有热量\(h\)。 我们设定`dist[1][0] = 0`因为我们从节点 1 开始，时间为零，热量为中性。 

2. 将初始状态 \((1, 0)\) 推入按累计时间排序的优先级队列中。 

3. 当优先级队列不为空时，提取已知时间最小的状态\((v, h)\)。 这确保了我们始终首先扩展当前最佳的部分路线，从而保留 Dijkstra 的贪婪性质。 

4. 对于每个出边\(v\)到\(u\)有时间成本\(l\)和热变化\(dt\)，计算新的热量\(h' = h + dt\)。 如果\(h'\)在外面\([-30, 30]\)，跳过此转换，因为它立即违反约束。 

5. 转换是否有效以及新时间\(dist[v][h] + l\)改善`dist[u][h']`，更新它并将 \((u, h')\) 推入优先级队列。 

6. 处理完所有可达状态后，答案是所有可达状态中的最小值`dist[n][h]`为了\(h \in [-30, 30]\)。 如果都是无穷大，则输出-1。 

我们不折叠每个节点的热状态的原因是未来的转换严重依赖于热，并且合并将丢失可行性信息。 

### 为什么它有效

 正确性取决于将每个 \((node, heat)\) 对视为具有非负边权重的较大有向图中的节点。 原始问题中的每条有效路径都与扩展图中的一条路径完全对应，反之亦然。 由于所有边权重都是非负的，Dijkstra 算法保证一旦某个状态以其最小距离弹出，后面的路径就无法改进它。 热约束是在边缘局部强制执行的，因此没有无效路径进入状态空间。 这确保我们永远不会放弃潜在的最佳路线，也不会接受无效的路线。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**18
OFFSET = 30
MAXH = 61

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())

    graph = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, l, dt = map(int, input().split())
        graph[u].append((v, l, dt))

    dist = [[INF] * MAXH for _ in range(n + 1)]
    dist[1][OFFSET] = 0

    pq = [(0, 1, OFFSET)]

    while pq:
        d, v, h = heapq.heappop(pq)
        if d != dist[v][h]:
            continue

        for to, cost, dh in graph[v]:
            nh = h + dh
            if nh < 0 or nh >= MAXH:
                continue
            nd = d + cost
            if nd < dist[to][nh]:
                dist[to][nh] = nd
                heapq.heappush(pq, (nd, to, nh))

    ans = min(dist[n])
    print(-1 if ans == INF else ans)
```该实现直接反映了扩展状态图的思想。 偏移量 30 用于映射热值\([-30, 30]\)进入数组索引\([0, 60]\)。 优先级队列确保按时间递增顺序处理状态。 

一个微妙的细节是陈旧状态检查`if d != dist[v][h]`，这可以避免处理过时的队列条目。 如果没有它，性能可能会因重复推送而显着降低。 

另一个重要的细节是最后迭代所有热值。 目标节点不需要特定的最终热量，只需要它位于边界内即可。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 |---|---|---|
 | 时间 | \(O(m \cdot 61 \log(n \cdot 61))\) | 每条边最多可以在 61 个热状态上进行松弛，并且每次松弛都会经过一个优先级队列 |
 | 空间| \(O(n \cdot 61 + m)\) | 距离表存储每个节点 61 个状态，邻接表存储边 |

 由于热范围是固定且狭窄的，因此常数仍然很小。 和\(n, m \le 10^5\)，这在具有二进制堆的 Dijkstra 下可以在限制内轻松运行。

 ## 边缘情况

 关键的边缘情况是当路径重新访问具有不同热状态的节点时。 该算法可以正确处理这个问题，因为它从不合并状态。 例如，到达节点 2 时的热量 -10 和热量 +10 是分开存储的，并且两者都是独立探索的。 

另一种情况是当所有路径都到达节点时\(n\)但沿途某处存在无效的热转换。 这些在转换步骤中会自动丢弃，因此最终的`min(dist[n])`正确地变成无穷大，产生-1。 

最后一个微妙的情况是当多个边连接具有不同热效应的同一对节点时。 该算法独立对待它们，确保在不假设边缘之间占主导地位的情况下发现最佳组合。
