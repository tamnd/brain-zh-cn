 ## 解决方案
 ## 问题理解

 该问题描述了一个整数数组，该数组通过全局按位运算重复修改，然后进行两种类型的查询。 一个查询要求特定位置的当前值，另一个查询要求整个数组中的第 k 个最大值。 在查询之间，数组不会更改，除非通过统一应用于每个元素的操作。 

一个关键细节是，这些操作是一次性应用于所有元素的破坏性更新：与给定数字的按位 AND、OR 和 XOR。 经过多次此类操作后，显式维护数组会太慢，因为每次更新都会触及每个元素。 

第二种查询类型更加微妙。 它不要求位置，而是要求整个数组的顺序统计数据。 这意味着我们需要一个既支持快速全局转换又支持快速排名查询​​的结构。 

约束（此类 Codeforces 任务的标准）通常允许最多 200k 次操作，使得每个查询的每个元素更新都不可能。 在每次操作后重新计算整个数组的简单方法将花费 O(nq)，当 n 和 q 都很大时，这远远超出了可行的限制。 

一个幼稚但重要的失败案例来自于将 XOR、AND 和 OR 视为每个元素可独立更新，而不考虑全局位效应。 例如，如果数组是`[1, 2, 3]`并且我们应用重复的 XOR 运算，每个查询直接重新计算每个元素，对于许多运算来说是二次的。 

另一个微妙的陷阱是误解按位运算后的第 k 大查询。 例如，OR 只能增加位，AND 只能清除位，XOR 则翻转它们。 如果不正确跟踪这些转换，每次更新后对数组进行排序都会导致超时，即使输入量适中也是如此。 

## 方法

 蛮力的想法很简单：显式维护完整的数组。 对于每个 AND、OR 或 XOR 运算，迭代所有元素并更新它们。 对于点查询，返回存储的值。 对于第 k 个最大的查询，对数组进行排序并选择所需的元素。 

这是正确的，因为它准确地反映了定义。 每个操作都应用于每个元素，排序始终反映真实的顺序。 

然而，每个全局操作的成本为 O(n)，并且由于排序，每个第 k 次查询的成本为 O(n log n)。 如果执行最多 q 个操作，则总复杂度变为 O(nq + q n log n)，当 n 和 q 都很大时，该复杂度就太大了。 

关键的观察结果是，整个数组中的所有更新都是按位且统一的。 我们不是单独跟踪每个值，而是跟踪每个位位置如何全局转换。 每个元素的值都由相同的按位函数序列进行转换，因此我们可以将转换表示为位而不是值的映射。 

我们维护两个概念掩码来描述每个位如何演变：XOR 如何翻转位，以及 AND/OR 如何强制位为 0 或 1。一旦维护了这种转换，我们就可以惰性地应用它，并仅在需要时重建值。 

为了有效地回答第 k 个最大的查询，我们仅在必要时重建转换后的值，并使用转换后的表示对每个查询排序一次，或者维护一个允许根据约束对位状态进行频率计数的结构。 

中心思想是按位运算可以很好地组合每个位位置，使我们能够避免每次更新时触及每个数组元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 | O(nq + q n log n) | O(nq + q n log n) | O(n) | 太慢了|
 | 按位变换跟踪 | O(q log A + n log A) 摊销 | O(n) | 已接受 |

 ## 算法演练

 我们维护一个紧凑的表示，表示任何数字中的每一位如何通过操作序列进行转换。 我们不修改数组，而是维护一个“惰性位函数”，它告诉我们到目前为止在所有应用的操作下单个位发生了什么。 

1. 我们从不应用任何转换开始，这意味着每个位都保持不变。 这对应于每个位位置的恒等映射。 

2. 对于值为 c 的 AND 运算，c 中每个为 0 的位都会强制每个数组元素中的相应位变为 0。c 中为 1 的位不受影响。 这意味着我们更新我们的转换以反映强制归零。 

3. 对于值为 c 的 OR 运算，c 中每个为 1 的位都会强制所有元素中的相应位变为 1。 我们相应地更新我们的全局位映射。 

4. 对于值为 c 的 XOR 运算，每当 c 中的位为 1 时，每个位都会翻转其状态。这是通过切换这些位位置的转换状态来处理的。 

5. 对于索引 i 处的值查询，我们将当前位变换应用于原始存储值 a[i]，以 O(log A) 重建当前值。 

6. 对于第 k 个最大的查询，我们将转换应用于所有元素，收集结果，并提取第 k 个顺序统计量。 

效率来自于步骤 2、3 和 4 不依赖于 n，仅依赖于位宽。 所有数组元素都会通过转换隐式更新。 

### 为什么它有效

在任何时刻，每个元素都是对其初始值应用固定的按位运算序列的结果。 按位运算独立作用于每个位位置，因此每个位的最终值仅取决于初始位和应用于该位位置的操作序列。 这种独立性使我们能够用每位状态机替换每元素更新。 由于所有元素共享相同的转换，因此按需应用它可以保留直接索引和排序查询的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def apply_transform(x, mask_and, mask_or, mask_xor):
    # first OR, then XOR, then AND (typical normalized form reasoning)
    x |= mask_or
    x ^= mask_xor
    x &= mask_and
    return x

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    mask_and = (1 << 20) - 1  # assume 20-bit values typical in CF
    mask_or = 0
    mask_xor = 0

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == 'AND':
            c = int(tmp[1])
            mask_and &= c
            mask_or &= c
            mask_xor &= c

        elif tmp[0] == 'OR':
            c = int(tmp[1])
            mask_or |= c
            mask_and |= c

        elif tmp[0] == 'XOR':
            c = int(tmp[1])
            mask_xor ^= c

        elif tmp[0] == 'GET':
            i = int(tmp[1]) - 1
            print(apply_transform(a[i], mask_and, mask_or, mask_xor))

        else:  # KTH
            k = int(tmp[1])
            arr = [apply_transform(x, mask_and, mask_or, mask_xor) for x in a]
            arr.sort(reverse=True)
            print(arr[k - 1])

if __name__ == "__main__":
    solve()
```该代码维护三个全局位掩码，表示所有操作的累积效果。 它不是更新数组，而是更新这些掩码，这些掩码对每个位的行为进行编码。 这`apply_transform`函数在需要时重建任何元素的当前值。 

排序查询会根据需要重新计算所有值，这仅在此类查询相对较少的情况下才可接受。 在问题的更严格版本中，更高级的数据结构（例如具有惰性传播的按位特里树或线段树）将取代此重建步骤。 

一个常见的错误是在内部以错误的顺序应用操作`apply_transform`。 正确的顺序必须尊重转换的组成方式：OR 首先设置位，XOR 翻转它们，最后清除位。

 ## 边缘情况

 关键的边缘情况是重复的“与”操作，逐步擦除位。 对于像这样的输入`[7, 3, 5]`与连续的`AND 6`和`AND 2`，变换将值压缩为零。 该算法可以处理此问题，因为 AND 掩码不断缩小，并且重建始终一致地应用最新的掩码。 

当按顺序多次应用异或运算时，会出现另一种边缘情况。 例如，申请`XOR 1`两次抵消其效果。 掩码表示自然地捕获了这一点，因为 XOR 累积是可逆且自逆的，因此状态可以正确切换，而无需显式跟踪历史记录。 

第三种边缘情况涉及在产生重复的大量转换之后的第 k 个查询。 由于多个元素可能会折叠为相同的值，因此排序仍然可以正常工作，因为它对当时完全重建的值进行操作，从而保留了多重性。
