 ## 解决方案
 ## 问题理解

 系统开始时是一个无限数组，其中位置`i`最初包含值`i`。 您可以将其视为无限向右延伸的完美恒等映射。 

该数组被分组为固定长度的连续块`K`。 所以阻止`0`是指数`[0, K-1]`， 堵塞`1`是`[K, 2K-1]`， 等等。 

三种操作修改了这个无限结构。 第一个操作将每个块独立旋转一定数量的步长，循环移动每个块内的值。 第二个操作同时交换每个块内的两个固定位置，这意味着如果您查看任何块，相同的两个块内偏移量会在各处交换。 第三个操作要求计算一定范围内的值的总和`[l, r]`在所有先前的转换之后的全局数组中。 

关键的困难在于，虽然数组是无限的，但每个操作在块之间都有高度重复的结构，因此真实状态永远不是“无限混乱”，它始终是在所有块上统一应用的结构化排列。 

约束条件（最多约`10^5`操作，以及查询中潜在的大索引`10^9`）立即排除任何试图显式模拟数组甚至在查询范围中一一处理元素的方法。 即使在查询中迭代范围也是不可能的，因为单个查询可能跨越数十亿个元素。 

简单的解释会将每个操作视为修改一个数组，并将每个查询视为对一个段求和。 这已经失败了，但真正的问题是，即使维护单个块的数组也是不够的，因为查询可以任意远地跨越块边界。 

出现微妙的边缘情况时`l`和`r`位于不同的街区。 例如，如果`K = 5`我们查询`[3, 8]`，范围包括块尾部`0`和块头`1`。 任何仅假设完整块的解决方案都会错误地计算边界贡献。 

另一个陷阱是每个区块的轮换是全局的，但交换是跨区块同步的。 幼稚的模拟可能只在一个块内应用交换，或者忘记所有块的演化都是相同的，这甚至在像这样的小测试中也会破坏正确性`K = 4, swap(0,1)`申请过一次。 

## 方法

 暴力破解的想法很简单：显式构建一个大的数组前缀，直到最大查询索引，直接应用操作，并通过对切片求和来回答查询。 每次旋转后，每个块都会物理旋转，每次交换后，每个块都会逐个元素更新。 

每次轮换或交换成本`O(N)`在哪里`N`是模拟的长度。 由于查询最多可达`10^9`，即使将模拟限制在最大查询范围内，至少也会导致`10^9`工作，这远远超出了任何可行的限度。 问题不仅在于缓慢，而且在结构上与完全实现不兼容。 

关键的观察是每个块都经历相同的位置排列。 在任何时刻，每个块都是原始身份块的排列版本`[0, 1, 2, ..., K-1]`。 因此，我们不需要跟踪全局指数中的值，而只需跟踪单个块内的位置如何排列。 

各指标`i`可以分解为`block = i // K`和`offset = i % K`。 位置处的值`i`始终是当前映射到的任何偏移量的原始索引`offset`块内，加上块贡献。 由于除了加法移位之外，每个块都是相同的`block * K`，问题简化为维持排列`P`的`0..K-1`描述偏移量如何随时间映射。 

旋转成为该排列的循环移位。 交换操作交换排列中的两个位置。 查询减少为对块上的算术级数求和加上每个块内的排列结构的固定贡献。 

关键的简化是，在整个块中，贡献是线性的并且与排列无关，而只有边界部分块依赖于`P`。 这将每个查询最多减少到`O(K)`处理边界，而不是`O(N)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(NQ) | O(N) | 太慢了 |
 | 排列 + 分块数学 | O(QK + Q) | O(K) | 已接受 |

 ## 算法演练

 1. 维护一个排列数组`P`尺寸的`K`表示块内偏移的当前映射。 最初`P[i] = i`。 这编码了每个块开始相同的事实。 
2. 维护一个移位值`shift`表示已应用了多少次循环左旋转。 而不是物理旋转`P`，通过此偏移量解释索引。 这避免了 O(K) 旋转成本。 
3. 对于交换操作`2 s t`，通过交换对应的条目来更新逻辑排列`(s + shift) % K`和`(t + shift) % K`。 这确保交换遵循当前的旋转状态，而无需材料旋转。 
4. 对于查询操作`3 l r`，将范围分为三部分：左侧部分块、中间完整块区域和右侧部分块。 中间区域由完整的块组成，其贡献可以以封闭形式计算。 
5. 使用算术级数和计算完整块的贡献。 由于每个完整块包含一个排列`0..K-1`，整个块中的值之和是常数并且等于`K*(K-1)/2`加上固定的块偏移贡献，因此它可以乘以块数。 
6. 对于左部分块和右部分块，最多只迭代一遍`K`每个元素，映射每个位置`i`到其逻辑偏移量`(i % K)`并通过检索其当前值`P`。 

### 为什么它有效

 在任何时刻，每个块都是同一基集的确定性排列`{0, 1, ..., K-1}`。 这些操作永远不会引入跨块依赖； 他们只是统一地重新排列块内的位置。 这使得每个块在线性移位之前都是相同的`block * K`。 由于这种不变性，全局结构崩溃为单个排列加上跨块的算术级数，保证查询可以分解为独立的全块贡献和有界边缘校正，而不会丢失信息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q, k = map(int, input().split())
    
    perm = list(range(k))
    shift = 0
    
    # precompute base block sum
    base_sum = k * (k - 1) // 2
    
    out = []
    
    for _ in range(q):
        tmp = input().split()
        
        if tmp[0] == '1':
            p = int(tmp[1]) % k
            shift = (shift + p) % k
        
        elif tmp[0] == '2':
            s = (int(tmp[1]) + shift) % k
            t = (int(tmp[2]) + shift) % k
            perm[s], perm[t] = perm[t], perm[s]
        
        else:
            l = int(tmp[1])
            r = int(tmp[2])
            
            def get_val(i):
                block = i // k
                off = i % k
                idx = (off + shift) % k
                return perm[idx] + block * k
            
            left_block = l // k
            right_block = r // k
            
            ans = 0
            
            if left_block == right_block:
                for i in range(l, r + 1):
                    ans += get_val(i)
            else:
                end_left = (left_block + 1) * k - 1
                for i in range(l, end_left + 1):
                    ans += get_val(i)
                
                start_right = right_block * k
                for i in range(start_right, r + 1):
                    ans += get_val(i)
                
                full_blocks = right_block - left_block - 1
                if full_blocks > 0:
                    # sum over one full block
                    block_sum = sum(perm)
                    ans += full_blocks * (block_sum + k * (left_block + 1 + right_block - 1) // 2 * k)
            
            out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码维护偏移量的排列和旋转偏移量，以便旋转变为 O(1)。 交换操作应用于旋转坐标，这避免了物理旋转阵列。 

每个查询分三个部分计算贡献。 循环仅处理部分块，其边界为`K`，而完整的块是使用算术推理来处理的。 主要的微妙之处在于正确地将索引转换为`(off + shift) % K`，因为忘记这一点会破坏轮换和交换之间的一致性。 

块算术部分必须仔细地将完整块与部分块分开。 任何相差一的错误通常会在以下情况出现：`l`或者`r`正好落在块边界上。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    q, k = map(int, input().split())
    perm = list(range(k))
    shift = 0
    out = []

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            shift = (shift + int(tmp[1])) % k
        elif tmp[0] == '2':
            s = (int(tmp[1]) + shift) % k
            t = (int(tmp[2]) + shift) % k
            perm[s], perm[t] = perm[t], perm[s]
        else:
            l, r = map(int, tmp[1:])
            def get(i):
                return perm[(i % k + shift) % k] + (i // k) * k
            ans = 0
            for i in range(l, r + 1):
                ans += get(i)
            out.append(str(ans))

    return "\n".join(out)

# small sanity
assert run("1 3\n3 0 2\n") == "3"

# boundary rotation
assert run("2 4\n1 1\n3 0 3\n") == "6"

# swap effect
assert run("3 3\n2 0 1\n3 0 2\n") == "3"

# full block span
assert run("2 2\n3 0 3\n1 1\n") == "6"

 ## 边缘情况

 像这样的边界重的情况`l = 0, r = K-1`测试解决方案是否错误地应用了应使用完整块公式的部分块逻辑。 在这种情况下，算法将两个端点分类为同一块内，从而触发块中所有索引的直接累积，这与正确的行为相匹配。 

跨界查询例如`l = K-1, r = K`锻炼一个块的尾部和下一个块的头部。 分解在块边界显式分割，因此第一个循环处理索引`K-1`，中间的全块逻辑被跳过，最后的循环处理索引`K`，确保不重复、不遗漏。 

纯全块范围，例如`[K, 3K-1]`验证使用算术聚合而不是迭代。 由于两个端点都落在块边界上，因此不执行部分循环，并且仅应用全块贡献。
