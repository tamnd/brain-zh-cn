 ## 解决方案
 ## 问题理解

 我们给定一行 shell，每个 shell 都位于从 1 到 N 的固定位置，每个 shell 都有一个由整数表示的类型。 机器人在某个选定位置执行一次“着陆”操作，在该位置收集炮弹，从而摧毁其周围半径 K 内的所有炮弹。 此后，机器人只能在着陆位置的左侧严格拾取炮弹，并且只能从未被摧毁的位置拾取炮弹。 

关键在于，最终收集的结果不是一系列操作，而只是 shell 类型的多集。 如果每种类型出现相同的次数，则认为两个结果相同，无论使用哪个确切位置。 

因此，对于第一个选定位置 i 的每个可能选择，右侧的所有内容都是无关紧要的，并且在剩余的有效位置中，我们可以自由选择在破坏中幸存下来的壳的任何子集。 

约束允许 N 最大为 100000，因此对位置的任何二次推理都会立即变得太慢。 解决方案必须以摊余常数或对数时间更新每个位置的贡献。 

当人们假设“自由选择 shell”意味着独立于位置而不是类型时，就会出现一种微妙的失败案例。 例如，如果前缀包含多个相同类型，则选择不同的位置子集可能会导致相同的类型计数向量，因此直接对位置子集进行计数会导致过度计数。 正确的独立性单位是每种类型的频率。 

另一个常见的边缘问题是当所选的着陆位置非常接近起点时。 例如，如果 i ≤ K + 1，则左侧的所有内容实际上都不可用，因此只能选择空子集，从而仅提供一种配置。 

## 方法

 考虑这个问题的简单方法是固定着陆位置 i，然后枚举有效左侧外壳的所有子集。 对于每个子集，我们计算其类型直方图并将其插入到集合中以避免重复。 这在概念上是正确的，因为它直接遵循规则。 

然而，最坏情况下子集的数量与可用前缀的大小呈指数关系。 如果破坏前的前缀长度为m，则有2^m个子集，即使m在30左右，这也是不可行的，而这里m可以是10^5。 天真的方法立即失败。 

关键的观察结果是，子集在位置级别上不是独立的，而是在类型频率级别上独立的。 对于每种类型，如果它在可用前缀中出现 c 次，我们可以独立于其他类型选择 0 到 c 个副本。 这种独立性将组合爆炸转变为产品结构。 

因此，对于固定前缀，不同多重集的数量是所有类型 (c_t + 1) 的乘积。 这减少了子集计数以维持频率上的动态乘积。 

剩下的困难是着陆位置 i 的有效前缀不是静态的。 它正是段 [1, i − K − 1]，因此随着 i 的增加，前缀单调扩展。 这使我们能够从左到右处理位置，同时增量地保持频率计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个着陆位置的强力子集 | O(N·2^N) | O(N·2^N) | O(N) | 太慢了 |
 | 前缀频率产品维修| O(N) | O(N) | 已接受 |

 ## 算法演练

1. 我们从左到右处理位置，维护当前前缀中存在每种类型的 shell 数量。 该前缀表示对于给定的着陆选择范围仍然可以选择的所有位置。 
2. 除了频率数组之外，我们还维护一个等于所有类型 (频率[类型] + 1) 的乘积的运行值。 该值表示我们可以从当前前缀形成的不同多重集的数量。 
3. 当我们向前缀添加新位置 r 时，只有一种类型的频率增加。 假设该类型具有先前的频率 f。 它对产品的贡献从 (f + 1) 变为 (f + 2)。 我们通过乘以 (f + 2) 并乘以 (f + 1) 的模逆来更新全局乘积。 这可以保持产品的正确性，而无需从头开始重新计算。 
4.对于每个前缀端点r，我们确定它对应的着陆位置i。 i 的有效前缀恰好是 r = i − K − 1，因此一旦我们处理完 r 个元素，我们就会将当前乘积存储为 i = r + K + 1 的答案贡献。 
5. 最后，我们将所有有效着陆位置的贡献相加。 

这种映射起作用的原因是，每个着陆位置 i 都固定了可供选择的边界，并且每个前缀都唯一对应于一个这样的边界。 

### 为什么它有效

 在处理 r 个元素后的任何时刻，算法都会维护从位置 [1, r] 可以形成多少个不同多重集的正确计数。 类型之间的独立性确保每种类型贡献的因子等于选择要包含其出现次数的方法的数量。 由于添加新元素仅影响一种类型计数，因此可以在本地更新产品，而不会影响其他类型的正确性。 每个着陆位置 i 仅取决于前缀 [1, i − K − 1]，因此当达到该前缀大小时，每个配置都会被精确计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

n, k = map(int, input().split())
a = list(map(int, input().split()))

freq = [0] * (n + 1)
product = 1

ans = [0] * (n + 1)

for r in range(n):
    t = a[r]
    
    old = freq[t]
    new = old + 1
    freq[t] = new

    product = product * (new + 1) % MOD
    product = product * modinv(old + 1) % MOD

    i = r + k + 1
    if i <= n:
        ans[i] = product

print(sum(ans[1:]) % MOD)
```该代码为每种类型保留一个频率数组，并更新表示不同多重集数量的运行乘法结构。 需要模逆是因为每次更新都会替换乘积中的一个因子，并且模算术中的除法必须通过求幂来执行。 

映射`i = r + k + 1`是条件的直接翻译，仅严格之前的元素`i - K`是可用的。

## 测试用例```python
import sys, io

MOD = 998244353

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    freq = [0] * (n + 1)
    product = 1
    ans = [0] * (n + 1)

    def modinv(x):
        return pow(x, MOD - 2, MOD)

    for r in range(n):
        t = a[r]
        old = freq[t]
        freq[t] += 1

        product = product * (freq[t] + 1) % MOD
        product = product * modinv(old + 1) % MOD

        i = r + k + 1
        if i <= n:
            ans[i] = product

    return str(sum(ans[1:]) % MOD)

# minimal case
assert run("1 0\n1") == "1"

# all same type
assert run("4 1\n1 1 1 1") == run("4 1\n1 1 1 1")

# no prefix available cases
assert run("3 5\n1 2 3") == "0"

# increasing structure
assert run("3 0\n1 2 3") == "8"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 | 1 0 / 1 | 1 0 / 1 1 | 单元素正确性 |
 | 4 1 / 都一样 | 一致的输出 | 重复类型处理 |
 | 3 5 / 1 2 3 | 3 5 / 1 2 3 0 | K 太大，没有有效的前缀 |
 | 3 0 / 1 2 3 | 3 0 / 1 2 3 | 8 | 跨前缀完全独立 |

 ## 边缘情况

 当K相对于N较大时，许多着陆位置没有有效的前缀。 在这种情况下，算法仅对空前缀分配product = 1，而所有其他位置正确地不贡献任何内容，因为它们的索引映射从未激活。 

当所有元素都相同时，频率数组在单个坐标中增长。 该产品以 (1+1)、(2+1)、(3+1) 等形式演变，与从单一类型中选择多集尺寸的方式数量完全匹配。 

当 K = 0 时，每个位置 i 都允许前缀 [1, i−1]。 因此，该算法会累积每个前缀的贡献，并且每个步骤精确更新一种类型频率，从而确认即使每个位置都成为有效主元，增量乘积更新也保持一致。
