 ## 解决方案
 ## 问题理解

 该问题给出了一棵由走廊连接的房间树，其中每个走廊都有遍历成本。 有些房间里有人在零时间开始“占据”该空间。 每个被占用的房间都会变得不安全，除非我们在人们到达该房间的时间之前到达那里，其中“到达时间”是由距任何最初占用的房间的最短路径距离决定的。 

我们每次从 1 号房间开始控制旅行者$t$，并且他以相同的边缘成本沿着走廊移动。 关键的限制是，只有当他到达时间小于或等于人们到达房间的时间时，他才可以进入房间。 如果他严格晚到，房间就会永远被封锁。 允许平等，这使得边界计时很重要。 

目标是选择最小的启动延迟$t$使得从房间 1 到房间至少存在一条有效路线$N$，保持在所有安全限制范围内。 

该结构意味着两个相互竞争的最短路径过程：一个从人员来源传播，另一个从从节点 1 开始、具有可变偏移量的旅行者传播。 

约束允许最多$10^5$节点和边，因此任何解决方案在实践中都必须本质上是线性的或接近线性的，通常$O(N \log N)$。 尝试为每个候选开始时间独立重新计算最短路径的解决方案将立即失败，因为即使是单个 Dijkstra 运行在这种规模下也已经很昂贵。 

平等处理产生了微妙的边缘情况。 如果旅客恰好在人们到达的时间到达，则房间仍然可用。 这意味着比较必须是非严格的。 例如，如果一个节点具有相等的距离，它仍然可用，而忽略相等性会导致不必要的阻塞。 

当存在多个初始源时会出现另一个问题。 来自单一来源的朴素 BFS 是不正确的，因为“人员到达时间”是一个多源最短路径问题。 

最后，有一种不明显的情况，即旅行者的最佳路径不是从 1 到 N 的全局最短路径。如果避开早期污染的节点，较长的路线可能是有效的。 因此，任何仅考虑从 1 开始的最短路径的解决方案都是不完整的。 

## 方法

 蛮力视图从猜测启动延迟开始$t$。 对于每位候选人$t$，我们模拟是否存在从 1 到 N 的路径，使得对于每个访问过的节点$v$，条件$$dist_1(v) + t \le dist_{people}(v)$$成立。 我们可以使用仅限于有效节点的 BFS 或 Dijkstra 重新计算可达性。 

这是正确的，但价格昂贵。 即使检查单个$t$成本$O(N \log N)$，尝试所有可能的值直到最大距离范围会导致不可能的结果$O(N^2 \log N)$或更糟糕的行为。 

关键的观察是可行性是单调的$t$。 如果延误$t$有效，然后任何更大的延迟$t' > t$只能让旅行者迟到而永远无法改善约束； 相反，它使条件更加严格。 这表明二分搜索$t$。 

使这个问题变得不平凡的原因是“固定的有效性”$t$”本身取决于节点约束下的最短路径。我们通过预先计算两个距离数组来解决这个问题：

 一是从所有有人占用的节点出发的多源最短路径，给出$dist_P[v]$。 

另一个是从节点 1 开始的最短路径，给出$dist_1[v]$。 

那么对于给定的可行性$t$简化为仅使用满足以下条件的节点来检查是否存在从 1 到 N 的路径：$$dist_1[v] + t \le dist_P[v]$$我们将其解释为由“有时安全”引起的子图$t$”节点。每次可行性检查都成为标准的图遍历。

 因此，问题变成了多源 Dijkstra、单源 Dijkstra 和阈值约束上的二分搜索的组合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力胜过一切$t$每次都进行完整搜索|$O(N^2 \log N)$|$O(N)$| 太慢了 |
 | 预计算距离+二分查找+BFS检查|$O(N \log N)$|$O(N)$| 已接受 |

 ## 算法演练

 1. 从所有包含人员的房间开始运行多源 Dijkstra。 这会产生$dist_P[v]$，人们最早到达每个房间的时间。 这是必要的，因为多个来源同时扩展，并且我们需要真正的最早到达。 
2. 从房间 1 运行标准 Dijkstra 进行计算$dist_1[v]$，旅客可以不受限制地到达每个房间的最早时间。 
3. 定义函数`can(t)`检查起始延迟是否存在有效路线$t$。 对于每个节点$v$，计算是否可用：$dist_1[v] + t \le dist_P[v]$。 将不可用的节点视为阻塞。 
4. 内部`can(t)`，从节点 1 运行 BFS 或 DFS，但仅遍历可用节点。 如果节点$N$可达，返回true。 
5.二分查找最小$t$这样`can(t)`是真的。 搜索范围可以由之间的最大可能差异来限制$dist_P$和$dist_1$，或者只是一个大的安全界限，例如总边权重总和或最大最短路径差。 
6. 输出最小有效值$t$。 

### 为什么它有效

 关键的不变量是对于固定的$t$，条件$dist_1[v] + t \le dist_P[v]$定义一组固定的允许顶点，与遍历顺序无关。 任何有效路径必须完全位于该集合内，并且该集合内的任何路径都遵循构造时的时序约束。 自从增加$t$仅缩小允许的集合，可行性是单调的，这证明了二分搜索的合理性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

INF = 10**18

def dijkstra(n, graph, sources):
    dist = [INF] * (n + 1)
    pq = []
    for s in sources:
        dist[s] = 0
        heapq.heappush(pq, (0, s))

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

def can(n, graph, dist1, distP, t):
    if dist1[1] + t > distP[1]:
        return False

    vis = [False] * (n + 1)
    stack = [1]
    vis[1] = True

    while stack:
        u = stack.pop()
        for v, _ in graph[u]:
            if not vis[v]:
                if dist1[v] + t <= distP[v]:
                    vis[v] = True
                    stack.append(v)

    return vis[n]

def solve():
    n, m, k = map(int, input().split())
    graph = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b, c = map(int, input().split())
        graph[a].append((b, c))
        graph[b].append((a, c))

    sources = list(map(int, input().split()))

    distP = dijkstra(n, graph, sources)
    dist1 = dijkstra(n, graph, [1])

    lo, hi = 0, max(distP[1], dist1[n]) + 1

    ans = -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if can(n, graph, dist1, distP, mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案将问题分为预处理和决策检查。 两个 Dijkstra 运行将时序信息与路径结构完全解耦。 

可行性检查避免重新计算最短路径。 相反，它将时间约束视为顶点过滤器，从而将每次检查减少为线性图遍历。 

二分搜索有效地包装了这个，这样只有$O(\log V)$需要这样的遍历。 

一个微妙的一点是条件中必须包含相等性`dist1[v] + t <= distP[v]`。 将其更改为严格不等式会错误地删除有效的边界情况，尤其是在最短路径对齐的示例中。

 ## 边缘情况

 一个关键的边缘情况是当起始节点对于小节点来说已经不安全时$t$。 在这种情况下，可行性检查会立即失败，因为节点 1 违反了约束$dist_1[1] + t \le dist_P[1]$，这会强制二分查找向上移动，直到不等式成立。 

另一种情况是唯一有效的路径需要绕行更长的路线。 该算法可以正确处理此问题，因为可达性是在过滤后的图上计算的，而不是依赖于最短路径结构。 

最后一种情况涉及多个人源的放置，使他们的波前在相同的时间相遇。 如果没有多源 Dijkstra，计算的到达时间将不正确，并且可能错误地将节点标记为安全或不安全，从而破坏可行性检查。
