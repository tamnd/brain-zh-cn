 ## 解决方案
 ## 问题理解

 我们给出了关于未知整数值的一系列陈述$y$。 每个语句都限制$y$相对于某个整数阈值$x$，并且是严格的或非严格的。 在每个陈述之后，我们还会被告知该陈述是真是假。 

任务不是确定$y$唯一，而是判断是否存在至少一个整数$y$这与所有给定的真实评估一致。 如果存在这样的值，我们必须输出任何一个有效整数。 否则，我们必须报告这些限制相互矛盾。 

每个查询都会缩小或扩展可能值的集合$y$。 一种自然的解释是，每一个陈述，取决于它是被肯定还是被否定，都会贡献一种形式的约束“$y$位于某个区间内或某个区间外”。如果所有这些约束至少在一个整数点上重叠，则最终答案存在。

 约束最多允许10000条语句，值可以达到$10^9$在大小上，因此任何逐一尝试候选值的方法都是不可行的。 对可能值范围的线性扫描将涉及最多$4 \cdot 10^9$检查，这远远超出了任何时间限制。 

一个微妙的边缘情况来自否定陈述所产生的矛盾。 例如，如果我们被告知$y > 5$是假的，那么$y \le 5$。 稍后，如果我们被告知$y \le 3$也是如此，它们可以与严格和非严格边界交互，从而很容易出现差一错误。 

当约束没有留下整数解时，即使实值区间仍然在端点处重叠，也会出现另一个棘手的情况。 例如，结合$y > 5$和$y < 6$是有效的，但结合$y \ge 6$和$y < 6$是不可能的。 

## 方法

 暴力方法会尝试每个整数$y$在允许的范围内$[-2 \cdot 10^9, 2 \cdot 10^9]$并检查它是否满足所有约束。 每张支票费用$O(n)$，因此总复杂度变为$O(n \cdot R)$， 在哪里$R$是域的大小，大约$4 \cdot 10^9$。 这太慢了。 

关键的观察是每个陈述仅约束$y$通过影响下限或上限。 每个条件，取决于它是被断言还是被否定，都可以重写为四种形式之一的简单不等式。 这意味着我们永远不需要跟踪任意集合，只需要跟踪最严格的下限和上限。 

因此，我们不是维护一组候选者，而是维护一个区间$[L, R]$处理每个语句后仍然可能的所有值。 每个查询都会通过将其与新约束相交来更新此间隔。 最终答案存在当且仅当$L \le R$处理好一切之后。 

这将问题从推理多种可能性减少到仅维护两个数字。

 | --- | --- | --- | --- |
 | 蛮力 |$O(n \cdot 4 \cdot 10^9)$|$O(1)$| 太慢了|
 | 间隔追踪|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们代表了所有可能的值$y$使用当前有效间隔$[L, R]$，最初覆盖所有整数。 

1. 初始化$L = -2 \cdot 10^9$和$R = 2 \cdot 10^9$。 这确保我们尊重输出约束，同时不会过早排除任何有效值。 
2.对于每条语句，解析操作符、阈值$x$，以及该陈述是真是假。 
3. 将每个语句转换为对的直接约束$y$。 如果该陈述为真，我们直接应用不等式。 如果为假，我们应用逻辑否定，这会翻转不等式的方向，并且通常将严格变为非严格（反之亦然）。 
4. 每个约束更新下限或上限：

 - 类似的条件$y > x$变成$L = \max(L, x + 1)$。 
- 类似的条件$y \ge x$变成$L = \max(L, x)$。 
- 类似的条件$y < x$变成$R = \min(R, x - 1)$。 
- 类似的条件$y \le x$变成$R = \min(R, x)$。 
5. 应用每个约束后，间隔$[L, R]$收缩。 如果在任何时候$L > R$，没有一个整数可以满足所有约束，所以我们立即得出不可能的结论。 
6. 处理完所有语句后，输出任意整数$[L, R]$， 例如$L$。 

为什么它有效

 每一步的间隔$[L, R]$准确地表示满足迄今为止所有已处理约束的整数集。 每个新约束要么在否定处理后删除低于阈值或高于阈值的值，要么删除两者。 由于每个约束都是线性且独立的，因此所有约束的交集始终是一个区间（或空）。 保持所有下界的最大值和所有上限的最小值就可以准确地保留该交集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 2_000_000_000

def apply(L, R, op, x, truth):
    if op == ">":
        if truth:
            L = max(L, x + 1)
        else:
            R = min(R, x)
    elif op == "<":
        if truth:
            R = min(R, x - 1)
        else:
            L = max(L, x)
    elif op == ">=":
        if truth:
            L = max(L, x)
        else:
            R = min(R, x - 1)
    else:  # "<="
        if truth:
            R = min(R, x)
        else:
            L = max(L, x + 1)
    return L, R

def solve():
    n = int(input())
    L, R = -INF, INF

    for _ in range(n):
        op, x, ans = input().split()
        x = int(x)
        truth = (ans == "Y")

        L, R = apply(L, R, op, x, truth)

    if L > R:
        print("Impossible")
    else:
        print(L)

if __name__ == "__main__":
    solve()
```该实现保持运行可行间隔。 辅助函数将每个查询转换为边界的直接调整。 最微妙的部分是正确处理否定：错误的陈述颠倒了不等式并改变了严格性，例如“not (y > x)”变成$y \le x$， 不是$y < x$。 

我们总是使用 max 来更新下限约束，使用 min 来更新上限约束，以确保我们永远不会错误地扩展可行区域。 最终选择回国$L$是安全的，因为区间内的任何整数都是有效的。

 ## 边缘情况

 一种极端情况是否定颠覆了严格性。 例如，如果语句是“$y > x$”，答案是“否”，正确的约束变为$y \le x$， 不是$y < x$。 该算法通过将每个运算符-答案对显式映射到精确的不等式来处理此问题，而不是尝试进行符号否定。 

另一个边缘情况是边界恰好在一点处相交。 如果我们最终得到$L = R$，只有一个有效整数。 返回任一边界仍然正确，并且实现返回$L$。 

最后一个例子是早期矛盾。 例如，从一个宽间隔开始，一个序列可以快速折叠它。 支票$L > R$确保一旦可行集变空，我们就逻辑终止，而不需要处理剩余的约束。
