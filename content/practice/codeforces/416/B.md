 ## 解决方案
 ## 问题理解

 我们有一条生产线，多幅画作通过固定顺序的画家进行移动。 每幅画必须按顺序经过所有画家，从第一个到最后一个。 每个画家在自己的队列中按顺序处理图片，并且他们不能同时处理多于一张图片。 然而，一旦画家完成了他在一幅画上的部分，该画立即可供下一位画家使用，他可能已经在等待或忙碌了。 

每张图片对于每个画家来说都有不同的处理时间。 目标是确定每幅画完成最后一个阶段的确切时刻，这意味着它离开了最终的画家。 

考虑这个问题的一个有用方法是具有多个阶段的管道。 每个阶段都有一个工作人员和一个作业队列，每个作业必须按顺序经过所有阶段。 困难在于，画家只有在前一个画家的图片到达并且画家空闲的情况下才能开始新的绘画。 

限制因素很重要。 图片的数量可以多达 50,000 张，而画家的数量最多为 5 个。这立即排除了任何逐步模拟时间或尝试独立重新计算每张图片的完整时间表的方法。 任何接近二次方的图片数量都会太慢。 

天真的误解通常来自于认为每张图片都可以作为其时间的总和来独立处理。 这将忽略管道阻塞引起的等待。 例如，如果两张图片都需要第一个画家很长时间，那么后面的画家可能会根据顺序而变得空闲或拥挤。 

如果我们假设每个画家在完成前一幅作品后立即开始一幅新画，就会出现另一个微妙的失败案例。 这忽略了这样一个事实：这幅画可能还没有来自前一位画家。 

一个小的说明性失败案例：

 输入：```
2 2
5 1
1 5
```如果我们错误地对每张图片求和，则两者都会在时间 6 完成。正确的行为是不同的，因为第二个画家在第一个画家释放第二张图片之前无法开始第二张图片，从而产生延迟。 

这就是核心挑战：顺序队列之间的全局同步。 

## 方法

 直接模拟将跟踪每个画家和每张图片何时可用以及画家何时空闲。 对于每幅画，我们都会将其传播给所有画家，更新可用时间。 这是正确的，但每张图片都需要 O(n) 个步骤，并且最多有 50,000 张图片，导致大约 250,000 次操作，这很好，但如果实现效率低下，对循环内等待条件的简单模拟很容易降低性能。 然而，真正的问题是，如果我们连续模拟时间或尝试搜索下一个可用时隙，它就会变得太慢。 

关键的观察是该系统具有严格的分层结构。 每个画家以固定的顺序处理图片，因此对于任何画家 j 和图片 i，开始时间仅取决于两个值：画家 j 何时空闲，以及图片 i 从画家 j−1 到达时。 当我们按顺序处理时，这两者都是已知的。 

这允许在 2D 网格上进行动态规划公式：dp[i][j] 是图片 i 完成画家 j 的时间。 每个状态仅取决于 dp[i][j−1] （来自前一个画家的到达）和 dp[i−1][j] （当画家在上一个图片之后空闲时）。 由于 n 很小，我们可以只维护前一行和当前行，甚至每个画家只维护一个一维数组。 

我们按照输入顺序处理图片，依次更新每个画家，维护每个画家前一张图片的完成时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(m·n) | O(m·n) | 已接受但矫枉过正|
 | 管道DP | O(m·n) | O(n) | 已接受 |

 ## 算法演练

 我们维护一个数组`finish[j]`表示画家j处理完上一张图片后空闲的时间。 

对于每张图片 i，我们逐步计算其完成时间。 

1. 初始化变量`current_time`这张图片到达画家 1 的时间。由于图片是按顺序处理的，所以这只是画家 1 空闲的时间，即。`finish[0]`。 
2. 对于从 0 到 n−1 的每个画家 j，计算该画家可以开始绘画的时刻。 这是图片从前一位画家到达的时间以及该画家从以前的工作中解放出来的时间的最大值。 那是：`start = max(current_time, finish[j])`。 
3. 画家的花费`t[i][j]`时间单位，因此该阶段的完成时间变为：`start + t[i][j]`。 
4. 更新`finish[j]`到这个新值，因为画家 j 现在正忙于绘制未来的图片。 
5. 将此完成时间向前传播为`current_time`，这成为下一位画家的到达时间。 
6.处理完所有的painter后，最终`current_time`是图片的完成时间。 

关键思想是，我们正在通过一条链模拟单个移动作业，其中每个站都有一个“忙碌直到”时间戳。 

### 为什么它有效

 在任何时刻，与在画家 j 处调度图片 i 相关的唯一信息是图片何时从 j−1 到达以及画家 j 何时空闲。 这两个值完全由先前处理的图片决定。 由于我们是按顺序处理图片的，`finish[j]`始终表示由较早图片引起的正确阻塞时间。 这个不变量确保我们永远不会覆盖有效的依赖关系，并且每个启动时间都是局部最优且全局一致的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    m, n = map(int, input().split())
    
    finish = [0] * n
    res = []

    for _ in range(m):
        t = list(map(int, input().split()))
        
        current = 0
        
        for j in range(n):
            start = max(current, finish[j])
            current = start + t[j]
            finish[j] = current
        
        res.append(current)

    print(*res)

if __name__ == "__main__":
    solve()
```该解决方案保持了管道状态的紧凑表示。 数组`finish`当每个画家有空时进行存储，并且`current`跟踪当前图片何时到达下一阶段。 

重要的细节是更新的顺序。 我们必须更新`finish[j]`仅在使用旧值计算开始时间之后。 这确保了我们不会意外地让画家比实际情况更早开始。 

每张图片都是独立处理的，但通过共享状态链接`finish`。

 ## 边缘情况

 一种极端情况是只有一名画家。 该系统退化为一个简单的序列，其中每张图片仅在前一张图片完成后才开始。 该算法自然地处理这个问题，因为`finish[0]`始终跟踪最后完成时间，并且`current`只是累积持续时间。 

另一种情况是后来的画家比早期的画家慢，从而导致瓶颈。 在这种情况下，`finish[j]`主导了许多图片的开始时间。 max操作确保没有图片能够绕过瓶颈，并且`current`正确地模拟队列的建立。 

最后一个微妙的情况是，当一幅画晚于画家的空闲时间到达时，这意味着画家必须等待。 这`max(current, finish[j])`明确地捕获这一点，防止消极或过早的调度并确保正确性而无需特殊处理。
