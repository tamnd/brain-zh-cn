 ## 解决方案
 ## 问题理解

 我们得到一个长度的数组$n$，最初全为零。 我们执行准确$n$操作，并且每个操作添加$1$到某个选定的连续段的每个元素。 在所有操作之后，我们可以任意重新排序数组，并且我们希望它匹配给定的目标值多重集$b$。 

该过程唯一重要的是每个索引被所选段覆盖的次数，因为每个覆盖都会对该位置贡献+1。 所以在所有操作之后，数组$a$只是一个覆盖计数数组$n$间隔。 

任务不是构造操作，而是最大化我们从操作中提取的最少信息：在所有有效构造中，我们希望最大化所选最长段的长度。 

关键约束是覆盖计数的最终多重集必须匹配$b$，但顺序并不重要。 这从目标中删除了位置结构并用频率要求代替。 

和$n$最多$2 \cdot 10^5$在测试用例中，任何模拟细分选择或尝试所有可能性的解决方案都是不可能的。 我们需要一个线性或接近线性的每个测试用例方法，因为任何比$O(n \log n)$总体而言，TLE 风险。 

一个微妙的边缘情况是$b$具有极度的不平衡性。 例如，如果$b = [n, 0, 0, \dots, 0]$，那么每次操作都必须覆盖一个索引，这意味着所有段都必须与该点相交，从而强制使用可以限制段长度的结构。 相反，如果所有值都是$1$，那么每个位置都必须被恰好覆盖一次，从而迫使不相交的单例行为，并且答案变得最小。 

一个天真的错误是假设既然我们可以重新排序，我们总是可以均匀地分布覆盖范围并使所有段都很长。 当高频值迫使少量位置出现许多重叠时，这种方法就会失败。 

## 方法

 每个操作为其区间内的每个元素贡献一个覆盖单位。 所以我们有效地分解了多重集$b$进入$n$长度线上的间隔$n$，其中每个位置的区间贡献之和等于$b_i$。 

如果我们忽略目标，问题就变成了标准区间多重集实现问题：我们必须表示一个度数序列（$b$）作为间隔发生次数的总和。 可行性条件保证这总是可能的。 

目标使事情变得复杂：我们希望最大化最大间隔长度。 如果我们尝试暴力破解，我们会尝试所有的选择$l, r$对于每个$n$操作，导致大约$O(n^2)$每个操作序列和总体指数组合的选择。 即使是带有回溯的贪婪构造也会爆炸，因为每个决定都会影响未来的可行性。 

关键的结构转变是查看排序后的最终数组。 由于顺序并不重要，我们可以想到$b$作为所需覆盖计数的多集。 每个操作都会向连续块加 1，因此每个操作都会在关联矩阵中贡献一个连续的“1”。 我们正在打包$n$间隔以使列总和匹配$b$。 

现在考虑什么限制了最大段长度。 如果我们希望所有段的长度至少为$k$，那么每次操作至少触及$k$职位。 这意味着所有操作贡献的总覆盖范围至少为$n \cdot k$。 但总覆盖范围也固定为$\sum b_i$。 这就给出了必要条件$n \cdot k \le \sum b_i$， 或者$k \le \frac{\sum b_i}{n}$。 仅此界限是不够的。 

更精确的约束来自于重叠结构不是自由的这一事实。 具有大的位置$b_i$迫使许多间隔通过它，并且这些间隔必须延伸穿过一个公共区域。 最大化段长度的最佳方法是“对齐”间隔，以便最密集的需求成为瓶颈。 

正确的观点是排序$b$按非递增顺序并将其解释为堆叠层。 最高值迫使许多间隔重叠的核心区域。 当我们向外扩展该区域时，所需的活动间隔数量就会减少。 最大分段长度取决于在所需覆盖范围低于剩余活动间隔数量之前我们可以延伸多远。 

这导致了贪婪模拟：我们尝试候选段长度$k$并通过模拟当我们从最密集的点向外移动时我们可以维持多少个“活动间隔”来检查可行性。 

而不是二分查找$k$明确地，我们可以通过处理排序数组并维护仍必须扩展的间隔来直接计算它。

 | --- | --- | --- | --- |
 | 所有操作的暴力构建|$O(n^2)$|$O(n)$| 太慢了|
 | 排序贪心可行性构建 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们首先对数组进行排序$b$按非递增顺序，以便我们始终首先处理最大的需求。 

1. 排序$b$按降序排列。 这确保我们在较弱的覆盖要求之前处理最受限制的覆盖要求，这决定了核心重叠结构。 
2. 维护一个变量$cur$，表示当前有多少个间隔是“活动的”并且必须延伸到下一个位置。 
3. 扫描已排序的值。 每一步$i$，我们从概念上决定至少必须覆盖多少个区间$i$第-层。 

我们更新$cur$以便它永远不会低于仍然需要覆盖的剩余高需求元素的数量。 
4. 最大可行段长度由以下最大值确定$k$这样，在满足所有所需的覆盖层之前，我们永远不会用完活动间隔。 
5. 答案被提取为该活动间隔过程的最大持续深度。 

关键思想是每个单元$b_i$对应于一个“层”，必须被经过位置的某个区间覆盖$i$。 最困难的部分是确保有足够的间隔保持活动状态以持续支持这些层。 

### 为什么它有效

 考虑从左到右分层构建间隔。 各单位在$b$是对覆盖该位置的一个区间的需求。 由于间隔是连续的，一旦间隔开始，它必须持续到结束，因此它会在各个位置上持续贡献。 排序顺序确保我们始终首先将间隔连续性分配给最高需求，这定义了必须同时活动的最小间隔数。 最大段长度正是在不违反覆盖要求的情况下可以维持该活动集的最大程度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))
        
        b.sort(reverse=True)
        
        cur = 0
        ans = 0
        
        for i, val in enumerate(b):
            cur = min(cur + 1, val)
            ans = max(ans, cur)
        
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案独立处理每个测试用例。 排序确保我们始终首先考虑最强的约束。 变量`cur`跟踪我们可以在当前“层深度”维持多少个间隔，同时`ans`记录最大可持续深度，对应于最大可能的段长度。 

过渡`cur = min(cur + 1, val)`抓住了这样的想法：每个新元素最多可以将活动所需层的数量增加一个，但我们不能超出该位置的需求。 这有效地模拟了可以同时强制通过不断增长的分段的间隔数量。

 ## 边缘情况

 对于像这样的输入$b = [0, 0, \dots, 0]$，算法立即产生$0$，因为不需要区间结构并且不能持续重叠。 排序后的扫描保持`cur`全程为零。 

对于严重倾斜的情况，例如$b = [n, 0, 0, \dots]$，第一个元素允许`cur`稍微增加，但随后的零立即使其崩溃，从而阻止任何长稳定段。 这符合单个密集点无法支持长均匀覆盖的直觉。 

对于像这样的均匀数组$b = [1, 1, \dots, 1]$，每一步增加`cur`为 1，然后将其钳位，产生稳定值 1，这反映出不可能有超出单例覆盖范围的重叠。
