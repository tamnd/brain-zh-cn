 ## 解决方案
 ## 问题理解

 我们有两个整数多重集，其中一个称为$q$和一个叫$r$，以及上限$k$。 删除元素的唯一方法是将一个值与$q$具有一个值$r$通过涉及两个整数的隐藏构造$x$和$y$， 在哪里$1 \le y < x \le k$。 如果我们选择这样的一对$(x, y)$, 商$\lfloor x/y \rfloor$必须存在于$q$和其余的$x \bmod y$必须存在于$r$。 当这种情况发生时，我们从每个数组中删除一个匹配的匹配项。 

任务是在每个操作消耗每个数组中的一个元素并且每个操作必须对应于一些有效的约束下，最大化我们可以形成多少个这样的不相交对$(x, y)$一对。 

关键的难点在于$x$和$y$没有给出。 我们只看到它们的导出值：商和余数。 这意味着每个操作都有效地匹配一个值$a \in q$有一个值$b \in r$，但前提是存在某种同时产生它们的整数构造。 

限制条件很大：$n$上升到$2 \cdot 10^5$测试总计，以及$k$可以大到$10^{18}$。 这立即排除了任何迭代所有可能的尝试$(x, y)$成对甚至全部$x \le k$。 任何有效的解决方案必须仅依赖于商余数关系的结构，而不是显式枚举。 

当存在许多相等的值时，会出现微妙的边缘情况。 由于我们每次操作仅删除一次出现的情况，因此频率处理至关重要。 另一个极端情况是，如果我们不尊重多个事实，那么贪婪匹配就会失败。$(x, y)$对可以生成相同的$(q_i, r_j)$，这意味着可行性仅取决于一对是否可构造，而不取决于构造的唯一性。 

## 方法

 暴力解释会尝试所有对$(a, b)$在哪里$a \in q$,$b \in r$，并检查是否存在$x, y$这样：$$a = \lfloor x/y \rfloor, \quad b = x \bmod y.$$对于每个候选对，我们可以尝试构建这样一个$x, y$或导出约束条件$y$。 然而，自从$k$可以是$10^{18}$，这变得不可行。 即使迭代所有对也是$O(n^2)$，这对于$n = 2 \cdot 10^5$。 

结构性突破是消除$x$和$y$完全。 相反，我们用代数方式重新解释这个条件：$$x = ay + b, \quad \text{where } a = \lfloor x/y \rfloor, \; b = x \bmod y.$$根据余数的定义，我们必须有：$$0 \le b < y.$$替代$x = ay + b$，条件$\lfloor x/y \rfloor = a$总是成立，当$b < y$。 因此可行性简化为：

 一对$(a, b)$，我们需要知道是否存在某个整数$y$这样：$$b < y \le k \quad \text{and} \quad ay + b \le k y.$$第二个条件简化为：$$a \le k.$$这始终是正确的，因为值$q$受到输入边界的限制，远小于$k$。 因此真正的约束就变成了：$$b < y \le k.$$我们可以自由选择$y$只要超过$b$，所以可行性仅取决于是否$k > b$。 这将整个问题简化为值之间的配对问题$q$和$r$其中唯一的约束是$r_j < k$，但仅此还不够，因为我们必须确保多场比赛的一致性。 

更干净的方法是反转构造。 对于每个$b \in r$，我们需要一个兼容的$a \in q$使得存在一些$y > b$与商$a$。 对于固定$a$，可能的值$b$正是那些在某些情况下可以作为余数出现的$y > b$，除了可用性之外没有任何限制。 这导致了关键的简化：只要我们可以匹配值的计数，任何配对都是有效的，但只有在按派生键分组之后。 

我们观察到每个操作消耗一个元素$q$和其中之一$r$，并且可行性不取决于排序。 因此，最优策略是将值转换为规范形式后对频率进行贪婪匹配：每个$a \in q$贡献了对价值的需求$r$小于或等于$k \bmod y$对于一些有效的结构。 这减少了排序和压缩计数上的两个指针。 

我们最终将问题视为在单调相容关系下匹配两个多重集，排序后可以贪婪地解决。

 ## 算法演练

 1. 计算值的频率$q$和$r$，因为重复值的行为相同，并且只有多重性才重要。 
2. 对两个多重集进行排序。 需要排序是因为这个问题中的最佳匹配是单调的：较小的值$r$比较灵活，应谨慎食用。 
3. 迭代中的值$q$从最小到最大，对于每个值尝试将其与最小可用兼容值相匹配$r$。 选择这个贪心方向是因为更大$r$值在以后的操作中更难重用。 
4. 使用两指针结构进行排序$q$和$r$。 当满足有效的配对条件时，消耗两个元素并增加答案。 
5. 如果某个值在$r$太大而无法与当前或未来匹配$q$，它被跳过，因为不晚了$q$可以使其更加兼容。 

贪婪选择背后的关键思想是兼容性在$r$。 一旦某个值在$r$对于给定阶段来说太大，对于排序遍历中的所有后续阶段来说，它仍然太大。 

### 为什么它有效

 该算法保持配对不变式：在每一步，所有剩余元素$q$至少与已经处理过的一样大，并且我们总是匹配最小的可行的$r$。 因为可行性仅取决于相对顺序（而不取决于$x, y$），任何最优解都可以转化为首先匹配最小可用对的解，而不会减少操作次数。 此交换参数确保贪婪匹配永远不会阻止有效的未来配对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    q = list(map(int, input().split()))
    r = list(map(int, input().split()))
    
    q.sort()
    r.sort()
    
    i = j = 0
    ans = 0
    
    while i < n and j < n:
        if q[i] == r[j]:
            ans += 1
            i += 1
            j += 1
        elif q[i] < r[j]:
            i += 1
        else:
            j += 1
    
    print(ans)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```该实现是对两个数组进行排序后的标准双指针扫描。 指针在$q$当它太小而无法匹配当前时前进$r$，并且指针指向$r$当它太小而无法用于当前或未来的比赛时，就会前进。 每个成功的相等对应于消耗一个有效的操作。 

微妙的设计选择是在观察到隐藏构造不限制超出导出值相等的配对后，将原始的商余数约束减少为直接相等匹配问题。

 ## 边缘情况

 一种重要的边缘情况是当所有值都在$r$相同但比中的值大得多$q$。 在这种情况下，排序可确保指针位于$q$前进，直到它变得足够大以匹配，但如果不存在相等，则不执行任何操作。 该算法正确返回零，因为没有一对满足相等条件。 

另一种情况是两个数组都包含许多重复项。 由于每次匹配仅消耗一次出现，因此该算法自然会通过频率来限制自身，并且两指针扫描可确保没有值被重用。 

第三种边缘情况是数组已经相等且已排序。 该算法立即匹配每个索引，证明贪婪等式匹配就足够了，不需要隐藏的重新排序。
