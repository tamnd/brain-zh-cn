 ## 解决方案
 ## 问题理解

 我们在编号为 1 到 n 的一维单元条上给出一个隐藏位置，其中 n 可以大到 10^9。 恰好有一个牢房里藏着一件埋藏的宝藏。 

我们可以通过选择一个单元格 i 并在那里有效地放置一个探测器来与法官进行交互。 在第一次放置之后，接下来的每个放置仅返回相对信息：它告诉新位置是否比前一个位置更接近、更远或处于相同距离。 答案是基于比较 |i - x| 的符号 |prev - x|，其中 x 是隐藏的宝藏位置，prev 是您之前的查询。 

任务是使用最多 60 个查询来识别准确的宝藏位置。 

重要的约束不是 n 本身，而是查询限制。 由于n高达10^9，任何直接扫描或密集探测都是不可能的。 即使是 O(log n) 的方法也必须仔细设计，因为每个“比较”可能会花费多个查询。 

一个微妙的问题是反馈不是绝对距离。 你永远不知道你离宝藏有多远，只知道相对于你之前的猜测，你是进步了还是恶化了。 这使得标准二分搜索变得不可能，除非我们首先将这种相对反馈转换为可用的比较原语。 

边缘情况主要与交互相关，而不是算法相关。 如果我们假设我们可以直接比较任意位置而不考虑“先前查询”约束，那么我们将错误地设计一个在实现过程中失败的标准二分搜索。 例如，除非我们在 20 之前显式查询 10，否则不允许直接比较 f(10) 和 f(20)。 

另一种边缘情况是搜索间隔压缩为单个点。 此时，必须避免任何额外的比较尝试，因为这会浪费查询并可能破坏交互协议。 

## 方法

 蛮力策略会尝试从 1 到 n 的每个位置。 这是正确的，但完全不可行，在最坏的情况下需要多达 10^9 次查询，这超出了限制几个数量级。 

关键的观察结果是函数 f(i) = |i - x| 是单峰的。 当我们从左侧接近 x 时，它严格减小，而在经过 x 后，它严格增加。 如果我们可以自由比较 f(i) 和 f(j)，我们就可以二分查找或三目查找最小值。 复杂的是我们不能得到 f 的直接值，只能得到连续查询之间的比较。 

关键的见解是单个“先前查询状态”足以模拟比较。 如果我们查询位置 a，然后查询位置 b，响应会告诉我们 f(b) 是大于还是小于 f(a)。 这意味着两个位置之间的每次比较恰好需要两次查询：一次用于建立参考点，另一次用于测试参考点。 

一旦我们可以比较相邻的中点，我们就可以对 f(i) 的最小值的位置执行标准的二分搜索，这正是宝藏的位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 太慢了|
 | 具有交互式比较的最佳二分搜索 | O(log n) 次查询（每步 2 次）| O(1) | O(1) | 已接受 |

 ## 算法演练

 我们维护一个保证包含宝藏位置的搜索区间 [l, r]。

1. 计算 mid = (l + r) // 2. 我们怀疑宝藏位于中间或一侧，具体取决于距离函数的斜率。 
2. 查询位置mid。 这还不会产生可用的比较，但它为下一个查询设置了参考点。 
3. 查询位置 mid + 1。响应现在将 f(mid + 1) 与 f(mid) 进行比较。 这为我们提供了有关我们是否离宝藏更近或更远的方向信息。 
4. 如果响应表明我们靠近了，即 f(mid + 1) < f(mid)，那么宝藏必须严格位于 mid 的右侧。 我们更新 l = mid + 1。 
5. 如果响应表明我们移动得更远，即 f(mid + 1) > f(mid)，则宝藏位于 mid 或其左侧，因此我们更新 r = mid。 
6. 重复这个过程，直到l == r，此时我们已经识别出宝藏。 

这样做的原因是相邻点之间的比较告诉我们单峰函数斜率的方向。 每一步都会消除一半的剩余搜索空间。 

### 为什么它有效

 函数 f(i) = |i - x| 对于 i < x 严格递减，对于 i > x 严格递增。 因此，比较 f(mid) 和 f(mid + 1) 可以揭示我们是位于最小值的左侧还是右侧。 因为每次比较都正确地识别哪一半不能包含最小值，所以 x 保留在 [l, r] 内的不变量在每一步之后都会保留，保证最终收敛到唯一的最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(i):
    print("?", i)
    sys.stdout.flush()
    return input().strip()

def solve():
    n = int(input())
    
    l, r = 1, n
    
    while l < r:
        mid = (l + r) // 2
        
        ask(mid)
        res = ask(mid + 1)
        
        if res == '+':
            l = mid + 1
        else:
            r = mid
    
    print("!", l)
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```关键的实现细节是，每次比较都被构造为两步交互：首先我们通过查询 mid 建立参考点，然后立即查询 mid + 1 以获得定向比较。 第一个查询的响应被故意丢弃，因为它只设置判断的内部状态。 

二分搜索边界更新直接来自于符号的解释。 “+”表示第二个位置更近，所以宝藏一定在右边。 任何其他反应都意味着相反的方向，我们可以安全地缩小正确的边界。 

必须注意每次查询后刷新输出。 在交互式问题中，即使逻辑正确，缺少刷新也会导致程序挂起。

 ## 边缘情况

 当 n = 1 时，循环永远不会执行，因为最初 l == r，因此我们立即输出 1。算法正确地避免了任何查询，遵守限制。 

当宝藏位于边界时，例如 x = 1 或 x = n，比较始终将区间推向正确的边缘。 例如，如果 x = 1，则 mid 和 mid + 1 之间的每次比较都将表明向右移动会增加距离，不断缩小 r 直到达到 1。 

当间隔大小变为 2 时，算法仍然可以正确运行，因为 mid 和 mid + 1 代表唯一有意义的比较对。 更新一步压缩了间隔，确保无需额外查询即可终止。
