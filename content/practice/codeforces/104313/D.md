 ## 解决方案
 ## 问题理解

 给定两个不相交的整数区间：一个区间代表 x，一个区间代表 y。 具体来说，x 必须严格选择大于 a 且至多 c，并且 y 必须严格大于 b 且至多 d。 任务是确定我们是否可以选择这样一个对 (x, y)，使得乘积 x·y 可以被乘积 a·b 整除。 如果存在多个有效对，则任何一个都是可接受的，如果不存在，我们必须报告不可能性。 

整除条件可以用更结构化的方式重写。 我们需要 a·b 来除 x·y，这相当于 a·b 中的每个质因数必须以至少相同的总指数出现在 x·y 中。 由于 x 和 y 是范围内的独立选择，因此问题变成了将 a·b 的素因数分布在两个有界变量上。 

所有端点的约束最多为 10^9，最多有 10 个测试用例。 这排除了枚举范围内候选值的任何尝试，因为即使单个范围也最多可以包含 10^9 个值。 任何解决方案都必须在每个测试用例的对数或恒定时间内工作，并且仅在端点上进行算术推理。 

当人们试图贪婪地将因子分配给 x 或 y 而不检查边界的可行性时，就会出现一种常见的失败情况。 例如，如果 a=6、b=10、c=7、d=11，则 x 必须在 (6,7] 中，因此 x=7，y 在 (10,11] 中，因此 y=11，但 7·11 不能被 60 整除。一种幼稚的方法可能会尝试局部调整一侧，但约束条件没有留下任何灵活性。

 另一个微妙的问题是假设选择 x=a 或 y=b 是有帮助的。 由于 x>a 和 y>b 被严格禁止，因此任何构造都必须严格在下限之上开始，这消除了最明显的因子共享策略。 

## 方法

 暴力解释很简单：尝试 (a, c] 中的每个 x 和 (b, d] 中的每个 y，并检查 x·y 是否能被 a·b 整除。这是正确的，但完全不可行。每个区间最多可以有 10^9 个值，因此乘积空间远远超出任何计算限制。

 关键的观察是我们实际上不需要搜索对。 我们只需要将 a·b 的一个有效因子分布为受区间约束的两个数字。 我们不再考虑产品，而是转向单独的可分割性约束。 

条件 a·b | x·y 相当于要求 x 包含足够多的 a·b 未被 y 补偿的质因数，反之亦然。 处理此问题的一种更简单的方法是强制其中一个数字（例如 x）成为 a 的倍数。 如果 x 可被 a 整除，则 x·y 可被 a·b 整除当且仅当 y 可被 b 整除，因为我们可以重写：

 x·y 可被 a·b 整除

 ⇔ (x/a)·(y/b) 是整数

 提供了 a|x 和 b|y。 

这将任务简化为查找 (a, c] 中的 x 可被 a 整除，以及 (b, d] 中的 y 可被 b 整除。问题变成检查每个区间中是否独立存在这样的倍数。

 然而，这种直接分割并不总是必要的。 我们只需要因子的任意分布，因此我们可以尝试两种对称结构：使 x 吸收所有 a·b 并设置 y=1，或者使 y 吸收所有 a·b 并设置 y=1，但由于边界，这些都是无效的。 正确的归约更简单：我们尝试通过选择将 a 的所有因子独立地放入 x 中，并将 b 的所有因子独立地放入 y 中：

 x = a 严格大于 a 的最小倍数

 y = b 严格大于 b 的最小倍数

 并验证它们是否在范围内。 如果满足，则条件自动成立，因为 x 是 a 的倍数，y 是 b 的倍数，因此 x·y 是 a·b 的倍数。 

如果任一区间不能提供这样的倍数，则不存在解决方案，因为我们无法满足该因子分量的整除性要求。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 计算满足 x > a 并且 x 可被 a 整除的最小整数 x。 这是有效范围内的第一个候选倍数。 
2. 如果 x 超过 c，我们已经知道 x 无法选择，因此在这种构造下不存在解。 
3. 计算最小整数 y，使得 y > b 并且 y 可被 b 整除，b 是 b 在其区间内的第一个候选倍数。 
4. 如果 y 超过 d，我们同样会在 y 方面失败。 
5. 如果 x 和 y 都存在于各自的边界内，则输出 (x, y)。 

每个步骤的驱动理念是：如果我们将 a 的因式分解完全分配给 x，将 b 的分解完全分配给 y，则可以保证乘积的整除性。 我们通过强制独立整除来避免 x 和 y 之间的任何耦合。 

### 为什么它有效

 该算法强制 x == 0 mod a 和 y == 0 mod b。 在这些约束下，x·y 可自动被 a·b 整除，因为 a 的素因数分解完全包含在 x 中，b 的素因数分解完全包含在 y 中。 由于 x 和 y 在其允许的范围内独立选择，因此满足两个模约束的任何有效构造都会产生正确的解，并且如果任一约束在其区间内没有可行的代表，则在此结构下不存在有效对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def next_multiple(g, l):
    # smallest multiple of g strictly greater than l
    return ((l // g) + 1) * g

t = int(input())
for _ in range(t):
    a, b, c, d = map(int, input().split())

    x = next_multiple(a, a)
    y = next_multiple(b, b)

    if x > c or y > d:
        print(-1, -1)
    else:
        print(x, y)
```辅助函数使用整数除法计算严格高于下限的给定基数的第一个倍数。 关键细节是使用 (l // g) + 1 而不是尝试增量搜索，这在大范围下会太慢。 

主循环只是独立地将其应用于 a 和 b，然后检查构造的值是否保持在允许的区间内。 构造后 x 和 y 之间不需要交互。 

## 工作示例

 考虑 a=3、b=4、c=10、d=15 的情况。 

| 步骤| x 计算 | y 计算 | 结果 |
 | --- | --- | --- | --- |
 | 1 | 3 > 3 的下一个倍数是 6 | 4 > 4 的下一个倍数是 8 | (6, 8) |

 这里两个值都在范围内，并且 6·8 显然可以被 12 整除，这证实了正确性。 

现在考虑 a=8、b=9、c=10、d=10 的情况。 

| 步骤| x 计算 | y 计算 | 结果 |
 | --- | --- | --- | --- |
 | 1 | 8 > 8 的下一个倍数是 16 | 9 > 9 的下一个倍数是 18 | x 超过 c |

 由于 x 不能放置在其区间内，因此即使 y 单独可行，也不存在有效的对。 

这些例子表明可行性是在每个轴上独立决定的。

 ## 边缘情况

 一种关键的边缘情况是 a 或 b 的唯一倍数正好位于上限之外。 例如，如果 a=5，c=9，则大于 a 的第一个有效 x 是 10，这已经违反了约束，因此即使间隔不平凡，也不存在 x 。 该算法正确计算出 10 并立即拒绝。 

另一种边缘情况是当 a 和 c 非常接近时，例如 a=10^9-1 和 c=10^9。 如果 a 没有除以 (a, c] 中的任何数字，则计算出的下一个多次跳转超过 c，在不扫描间隔的情况下正确地发出不可能性的信号。

 最后一种情况是两个间隔都很大但一个碱基已经接近边界，例如 a=6、c=6 和 b=4、d=100。 由于 x 必须严格大于 6，因此 x 会跳转到 12 并失败，即使 y 有很多选项。 检查的独立性确保了正确的拒绝，而不考虑不必要的组合。
