 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 在每个测试用例中都有一个整数数组，然后是一系列操作。 每个操作都基于奇偶校验来定位数组：一种类型为每个偶数元素添加固定值，另一种类型为每个奇数元素添加固定值。 每次操作后，我们必须报告数组的总和。 

关键的困难在于，数组在每次查询后在概念上都会发生变化，但我们不会被要求输出数组本身，只输出其总和。 这些约束清楚地表明，每个测试用例的元素数量和操作数量都可以达到 100000，所有测试的总和以 200000 为界。这立即排除了在每次操作后从头开始重新计算总和，因为这将导致大约 O(nq)，这将超出时间限制几个数量级。 

需要考虑的自然边缘情况是奇偶校验动态变化时。 例如，如果我们将所有偶数加 1，其中一些就会变成奇数。 幼稚的方法可能会尝试错误地更新计数或总和，而不考虑这种转变。 

考虑这个小例子：

 输入：

 n = 3, a = [1, 2, 3]

 查询：偶数加10

 正确的数组变为 [1, 12, 3]，sum 仅增加 10 一次（因为只有一个偶数元素存在）。 一个天真的错误是假设奇偶校验集是固定的，并且只是乘以初始计数，而不跟踪元素如何随时间在奇偶校验类之间移动。 一旦更新累积，这就会变得错误。 

基本的观察是奇偶性在加法下不稳定，因此我们无法维持索引的固定划分。 相反，我们需要跟踪当前存在多少个偶数和奇数，以及它们的总和如何演变。 

## 方法

 暴力解决方案直接模拟每个操作：扫描整个数组，检查每个元素的奇偶校验，在适当的时候应用更新，然后重新计算总和。 这是正确的，因为它完全反映了问题陈述。 然而，每次查询的成本为 O(n)，当 q 达到 100000 时，总工作量变为 O(nq)，在最坏的情况下达到 10^10 次操作，远远超出了限制。 

关键的见解是我们实际上在任何时候都不需要完整的数组。 我们只需要三个信息：偶数元素之和、奇数元素之和以及每组有多少个元素。 一旦我们维护这些聚合，每个操作就变成一个恒定时间的更新。 

当我们将 x 添加到所有偶数元素时，每个偶数元素都会增加 x，因此总和会增加 x 乘以偶数元素的数量。 然而，奇偶校验发生了变化：所有这些偶数元素随后都变成了奇数。 因此，我们必须将它们的计数和贡献从偶数桶转移到奇数桶。 相同的逻辑对称地适用于奇数更新。 

这将问题从按元素模拟转变为按组记账。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nq) | O(n) | 太慢了|
 | 最佳| O(n + q) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们在整个过程中维护四个值：偶数元素的计数、奇数元素的计数、偶数元素的总和以及奇数元素的总和。

1. 通过扫描一次数组来初始化，将每个元素分类为偶数或奇数。 我们相应地累积计数和总和。 这为我们提供了整个数组的压缩表示。 
2. 计算初始总和作为偶数和奇数贡献的总和。 该值将在每次查询后增量更新。 
3. 对于“将 x 添加到所有偶数元素”类型的查询，我们首先计算由于此操作而导致的总和增加了多少，即 x 乘以偶数元素的数量。 这是因为每个偶数元素都只增加一次。 
4、更新总额后，要体现结构变化。 每个偶数元素在添加x后都变成奇数，因此整个偶数桶被转移到奇数桶中。 我们通过将旧的偶数和加上 x 乘以偶数计数来更新奇数和，然后将偶数和重置为零。 
5. 我们还更新奇偶校验计数：所有偶数元素都变为奇数，因此 odd_count 增加了 Even_count，而 Even_count 变为零。 
6. 对于“向所有奇数元素添加 x”类型的查询，我们应用对称逻辑：将总和增加 x 乘以 odd_count，将所有奇数质量移至偶数桶中，并相应地更新计数。 
7、每次查询后，输出当前总和。 

正确性取决于将元素正确划分为两个不断发展的组，其中每个组完全代表当前的偶数或赔率。 

### 为什么它有效

 在任何时刻，每个元素都恰好属于两个不相交集合之一：当前偶数值和当前奇数值。 每个操作仅对一组应用统一变换。 由于所选集合中的所有元素都接收相同的增量，因此它们的相对奇偶校验会一致翻转，并且没有元素分裂或与同一组中的其他元素表现不同。 这允许通过计数和总和来汇总整个状态，而不会丢失信息，并且每个转换都保留组总和和计数与底层数组完全匹配的不变式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        even_cnt = 0
        odd_cnt = 0
        even_sum = 0
        odd_sum = 0

        for v in a:
            if v % 2 == 0:
                even_cnt += 1
                even_sum += v
            else:
                odd_cnt += 1
                odd_sum += v

        total = even_sum + odd_sum
        out = []

        for _ in range(q):
            typ, x = map(int, input().split())

            if typ == 0:
                total += x * even_cnt
                odd_sum += even_sum + x * even_cnt
                odd_cnt += even_cnt
                even_sum = 0
                even_cnt = 0
            else:
                total += x * odd_cnt
                even_sum += odd_sum + x * odd_cnt
                even_cnt += odd_cnt
                odd_sum = 0
                odd_cnt = 0

            out.append(str(total))

        print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码维护聚合信息而不是完整数组。 初始化循环将元素分类到奇偶校验组中。 每个查询直接更新总和，然后执行一组到另一组的完整传输，反映加法后的奇偶校验翻转。 最微妙的一点是，将 x 添加到组后，该组中的每个元素都会更改奇偶校验，因此我们必须将整个累加和和计数移动到相反的存储桶中，而不是部分更新值。 

必须注意的是，在重置计数器之前，总和更新会使用旧状态，否则传输的质量将会丢失。

 ## 边缘情况

 当重复操作完全崩溃一个奇偶校验组时，就会出现一种极端情况。 例如，从所有偶数开始并对偶数应用奇数增量，立即将每个元素移动到奇数桶中。 

输入：

 n = 2, a = [2, 4], 查询 (0, 1)

 初始状态：

 偶数_cnt = 2，偶数_sum = 6

 操作后：

 每个元素都变成奇数： [3, 5]

 该算法将总和更新为 2 * 2 = 4，得到 10，并将整个偶数状态转换为奇数状态。 甚至计数器也降为零。 由于所有元素统一改变奇偶校验，因此表示保持一致。 

另一个微妙的情况是当多个连续操作针对已经为空的奇偶校验组时。 更新公式使用计数，因此乘以零可确保不会发生不正确的漂移，并且状态保持稳定而无需特殊外壳。
