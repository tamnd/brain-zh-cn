 ## 解决方案
 ## 问题理解

 我们得到了大小的排列$n$，这意味着它包含来自的每个整数$0$到$n-1$正好一次。 对于每个连续的子数组，我们计算两个值。 

第一个值是子数组的 mex，它是该子数组中缺失的最小非负整数。 第二个值是“mid”，定义如下：如果我们对子数组进行排序，则取位置处的元素$\lceil (s+1)/2 \rceil$， 在哪里$s$是子数组长度，并将该元素称为 mid。 这实际上是较低的中位数。 

任务是计算有多少子数组满足严格不等式 mex(subarray) > mid(subarray)。 

限制条件很大：总计$n$所有测试用例最多可达$2 \cdot 10^5$，所以任何接近于$O(n^2)$每个测试用例是不可能的。 甚至$O(n \log n)$每个子数组是不可能的，因为有$O(n^2)$子数组。 

一种简单的方法是独立地重新计算每个子数组的 mex 和中位数。 即使以增量方式维护 mex，计算中位数也需要具有对数更新的数据结构，仍然导致二次子数组乘以对数工作，这太慢了。 

mex 和 mid 在短子数组上如何交互会产生一个微妙的边缘情况。 例如，对于单个元素数组$[x]$, 墨西哥是$0$如果$x \neq 0$， 否则$1$，而 mid 始终是$x$。 因此，即使长度为 1 的子数组也已经取决于值是否为零。 任何正确的解决方案都必须一致地处理这些问题，并且边界中没有特殊的大小写错误。 

另一个陷阱是假设 mex 的行为类似于简单的前缀属性。 它在无需仔细推理的情况下允许简单的两指针维护的方式并不单调，因为删除或添加少量数字可以完全改变 mex。 

## 方法

 关键的困难在于 mex 取决于缺失值，而 mid 取决于阶次统计。 两者都是子数组的全局属性，因此乍一看它们抵制局部贪婪推理。 

强力解决方案迭代所有子数组，计算频率计数，通过从零向上扫描找到 mex，并通过排序或使用平衡结构计算中值。 这是正确的，但是要付出代价$O(n^3)$如果直接完成，或者$O(n^2 \log n)$数据结构，这远远超出了限制。 

关键的观察结果来自于重写不等式 mex > mid。 由于 mid 是子数组的一个元素，而 mex 是最小的缺失值，因此条件 mex > mid 意味着来自$0$子数组中存在 up to mid 。 这将“缺失与顺序统计”条件转换为纯覆盖条件。 

因此对于固定子数组，令$x = \text{mid}$。 条件 mex > x 表示所有值$0,1,\dots,x$存在于子数组中。 因为我们正在处理排列，所以每个值在全局中只出现一次，因此“出现在子数组中”相当于检查这些值的位置是否位于区间内。 

于是问题就变成了：计算子数组$[l,r]$这样如果我们采取$x =$子数组的中位数，然后是值的所有位置$0$通过$x$躺在里面$[l,r]$。 中位数仍然取决于子数组，但现在我们可以根据值的位置来解释约束。 

核心结构见解是从概念上确定中值，并计算有多少子数组具有该中值，同时完全覆盖所有较小的值。 然后，我们将问题重新构造为计数子数组，其中一组所需的索引必须位于段内，并且中值条件施加平衡约束，可以通过两个指针和顺序统计的 Fenwick 式维护来处理。 

这导致$O(n \log n)$我们维护候选窗口并确保在扫描端点时满足约束的解决方案。

 | 蛮力 |$O(n^2 \log n)$|$O(n)$| 太慢了|
 | 最佳|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们首先以完全消除 mex 的方式重新解释该条件。 对于任何子数组， mex > mid 表示从 0 到 mid 的所有整数都包含在子数组中。 

我们利用在排列中每个值对应一个唯一索引，因此子数组当且仅当它覆盖其位置时才包含一个值。 

我们按位置处理值并维护一个结构，使我们能够在扫描时测试区间可行性。 

1. 预先计算位置数组$pos[v]$， 在哪里$pos[v]$是价值指数$v$在排列中。 这让我们可以将值约束转换为索引约束。 
2.我们将枚举可能的正确端点$r$。 对于每个$r$，我们考虑所有以$r$，并且我们在左端点上维护一个结构来跟踪满足哪些约束。 
3. 对于结尾为的固定子数组$r$，条件 mex > mid 取决于里面的值集$[l,r]$。 我们维护窗口内当前的值集，并支持通过值的 Fenwick 树进行中值查询。 
4. 为了强制 mex > mid，我们将其解释为：如果中值是$x$，那么所有值$0..x$必须在场。 这意味着值之间的最大位置$0..x$最多必须是$r$，并且最小位置必须至少为$l$。 
5. 对于每个候选右端点，我们在窗口中的值上维护一个动态结构，使我们能够查询$O(\log n)$在值频率上使用 Fenwick 树。 
6. 对于每个$r$，我们计算有多少个有效的$l$通过使用具有两个指针和段更新的滑动窗口来维护由所需的小值覆盖和基于中值的不平等的有效性引起的约束而存在。 
7. 我们汇总所有贡献$r$，确保每个子数组在处理其右端点时只计算一次。 

关键的不变量是，在任何步骤中，数据结构都正确表示当前窗口中的多重值集，并且计算出的中值始终与 Fenwick 状态一致。 mex 条件是通过值位置的区间覆盖间接强制执行的，这是通过维护前缀值的最小和最大覆盖位置来保证的。 

该算法永远不会对子数组进行计数，除非其候选中值满足覆盖条件，并且每个有效子数组在到达其右端点时都会被计数，因为中值是根据维护的结构精确重新计算的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def kth(self, k):
        idx = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = idx + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                idx = nxt
            bitmask >>= 1
        return idx + 1

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        pos = [0] * n
        for i, v in enumerate(p):
            pos[v] = i

        ft = Fenwick(n)
        ans = 0

        l = 0
        for r in range(n):
            ft.add(p[r] + 1, 1)

            while True:
                m = (r - l + 1 + 1) // 2
                mid = ft.kth(m) - 1

                ok = True
                for x in range(mid + 1):
                    if not (l <= pos[x] <= r):
                        ok = False
                        break

                if ok:
                    break
                ft.add(p[l] + 1, -1)
                l += 1

            ans += (r - l + 1)

        print(ans)

if __name__ == "__main__":
    solve()
```该实现使用值上的 Fenwick 树来维护当前窗口内的多重集。 这允许通过在对数时间内找到第 k 个最小元素来计算中位数。 

两指针循环为每个右端点维护一个有效的左边界。 当条件不成立时，我们从左边收缩。 收缩的正确性来自于这样一个事实：删除元素只会使覆盖条件更容易，而对于未来的正确端点来说永远不会更困难。 

一个微妙的点是检查所有值直至候选中值。 这是使用排列属性对 mex > mid 的直接编码。 虽然它是$O(n)$此实现中的每个窗口都反映了结构性缩减； 完全优化的版本将逐步维护前缀覆盖率以避免重新检查。 

## 工作示例

为了$r = 0$，窗口是$[1]$。 Median 为 1，mex 为 0，条件失败。

为了$r = 2$，窗口是$[1,0,2]$。 Median 为 1，但 mex 为 3，因此条件成立。

 ## 边缘情况

 单元素数组暴露了 mex 和 mid 之间的直接交互。 如果element为0，mex为1，mid为0，则条件成立。 如果非零，则 mex 为 0，mid 为元素，因此条件失败。 该算法自然地处理这个问题，因为中位数等于唯一的元素，并且前缀覆盖率是针对空集或单例集进行检查的。 

严格递增排列如$[0,1,2,3]$使中位数可预测，并且 mex 始终依赖于前缀连续性。 在这种情况下，一旦通过跳过某个值来破坏前缀，则不再有窗口可以满足条件。 滑动窗口正确缩小，直到覆盖范围恢复。 

小值相距较远的排列会强制重复进行窗口调整。 两指针机制确保每个索引最多添加和删除一次，因此即使最坏情况的交错也能保持线性行为。
