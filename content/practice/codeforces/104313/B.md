 ## 解决方案
 ## 问题理解

 我们有一组 n 个孩子，每个孩子收集一定数量的栗子，然后将它们放在一堆。 第一个孩子萨沙首先将栗子放入堆中。 接下来的每个孩子贡献的栗子都是前一个孩子的两倍。 因此，贡献形成了一个几何级数，从 Sasha 的未知量 a 开始，然后是 2a，然后是 4a，依此类推，直到第 n 个孩子。 

我们还得到了 Sasha 计算出的总和 m。 任务是检查这个总数是否可以由某个整数起始值 a 产生，如果可能，则确定 a 必须是什么。 

问题的结构迫使总和采用非常严格的形式。 对于固定的 n，总数始终是已知常数的 a 倍，即 1 + 2 + 4 + ... + 2^(n-1)。 这已经表明整个问题简化为检查整除性并从固定乘数重建单个未知数。 

约束n ≤ 100 和m ≤ 10^18 表明涉及的值可以很大，但序列长度很小。 这排除了对大范围值进行模拟的任何需要，但也警告我们避免幼稚的算术，如果在其他语言中不小心处理，这些算术可能会溢出。 在 Python 中，这不是一个问题，但概念的正确性仍然很重要。 

当 m 不能被几何和整除时，会出现微妙的边缘情况。 在这种情况下，不存在有效的 a。 另一个极端情况是计算的 a 为零或负数，但由于 m ≥ 1 并且所有项都是 a 的正倍数，因此如果存在解，a 也必须为正数。 

## 方法

 思考这个问题的一种天真的方法是尝试从 1 到 m 的所有可能值，并模拟 n 项的序列 a, 2a, 4a, ...，检查总和是否与 m 匹配。 原则上这是正确的，因为每个有效配置都恰好对应一个 a。 然而，对于每个候选 a，我们将计算 n 项，在最坏的情况下给出 O(mn) 次操作。 当 m 达到 10^18 时，这是完全不可行的。 

关键的观察结果是该序列在 a 中是线性的。 总和可以分解为：

 S = a (1 + 2 + 4 + ... + 2^(n-1))

 括号中的表达式是仅取决于 n 的固定几何和。 这将问题从搜索可能的序列转变为简单的算术检查：计算乘数，检查 m 是否可被它整除，并将 a 恢复为 m 除以该乘数。 

唯一的微妙之处是安全地计算几何和。 由于 n ≤ 100，总和 2^n 完全在 Python 的整数容量范围内，但通常我们必须迭代计算它或使用位移位而不是依赖浮点运算。

 ## 算法演练

 我们使用序列的结构重写总和。 

1. 计算除缩放之外的所有孩子的贡献对应的几何乘数，即 1 + 2 + 4 + ... + 2^(n-1)。 这可以从 1 开始迭代构建，并重复加倍和相加。 
2. 维持从 1 开始的运行值 cur，以及从 1 开始的和乘数 s。对于剩余的 n-1 个子项中的每一个，将 cur 加倍并将其添加到 s。 这将构造两个幂的精确和，而无需担心溢出。 
3. 计算完s后，检查m是否能被s整除。 如果它不可整除，则没有整数起始值 a 可以产生给定的总和，因此答案是不可能的。 
4. 如果整除性成立，则计算 a = m / s。 这是 Sasha 贡献的唯一可能值，因为所有其他贡献都是它的固定倍数。 
5. 输出成功以及a。

### 为什么它有效

 贡献序列恰好是固定向量 (1, 2, 4, ..., 2^(n-1)) 的缩放版本。 任何有效的总和都必须位于由该向量生成的一维晶格上。 计算出的总和 s 是该向量的精确系数，因此任何有效总和必须等于 s 乘以单个标量 a。 由于所有贡献都是正整数，因此重构时不存在歧义，整除性充分表征了可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    s = 1
    cur = 1
    for _ in range(n - 1):
        cur *= 2
        s += cur

    if m % s != 0:
        print("No")
        return

    a = m // s
    print("Yes")
    print(a)

if __name__ == "__main__":
    solve()
```该解决方案直接反映了算法。 该循环构建几何和，而不依赖于在其他语言中可能溢出的公式。 可除性检查确保重建的起始值是整数。 

一个常见的实现错误是尝试直接使用封闭形式 2^n - 1，而不考虑指数处理中的溢出或差一错误。 迭代构造避免了这两个问题并使关系变得明确。

 ## 边缘情况

 关键的边缘情况是 n = 1 时。乘数 s 只是 1，因此任何 m 都是有效的，并且 a 必须等于 m。 该算法处理这个问题是因为循环运行零次并且 s 保持为 1，无需特殊处理即可保持正确性。 

另一种情况是 m 不能被几何和整除。 例如，n = 3 且 m = 8 得出 s = 7。算法计算出 8 % 7 ≠ 0 并立即拒绝这种情况。 这符合有效总数形成 7 倍数算术格的结构约束。 

最后，像 n = 100 这样的大 n 值仍然可以安全地运行，因为迭代加倍从不依赖于浮点算术或近似值。 每个值都经过精确计算，即使在上限也能确保正确性。
