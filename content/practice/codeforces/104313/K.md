 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并且允许我们使用非常具体的操作来修改它。 数组中的每个位置最多可以使用一次，当我们使用位置 i 时，我们将该位置的值乘以 i。 我们的目标不是最大化或最小化数组本身，而是使所有数组元素的乘积能够被 2 的幂整除。 

更具体地说，我们希望所有元素的总乘积至少包含 2 的 n 个因数。我们可以将其视为跟踪 2 除该乘积的次数。 每个数字都会贡献一些初始数量的因子 2，并且每个允许的操作都可以根据所选索引增加该贡献。 

输入包含多个独立的测试用例。 每个测试用例都给出一个数组，我们必须计算所需的索引操作的最小数量，以便乘积的 2 次方至少为 n，或者确定即使使用每个索引一次也是不够的。 

约束表明每个测试 n 可以大到 100000，并且测试的总和最多可达 200000。这排除了每个测试的任何二次甚至 n log n 方法，除非每个元素的工作量非常小并且使用线性聚合。 任何解决方案必须本质上以线性时间处理每个测试用例。 

一些边缘情况值得尽早隔离。 

如果初始数组的乘积中已经有足够的因数 2，则答案为零。 例如，如果 n = 4 并且数组为 [8, 1, 1, 1]，则乘积已包含至少 3 个 2 的因数，因此不需要进行任何操作。 

如果即使对每个指标进行运算后，乘积仍然没有达到所需的 2 的幂，则答案必须为 -1。 当数组值都是奇数并且索引不能提供足够的附加因子 2 时，就会发生这种情况。 

一个天真的错误是假设重复应用操作或贪婪地选择指数而不跟踪贡献会导致正确性。 例如，首先选择小指数可能看起来无害，但指数值直接控制它贡献的2的幂的多少，因此选择必须是全局最优的。 

## 方法

 直接的强力方法将尝试索引的每个子集，模拟应用该操作，并计算乘积中两个的结果指数。 对于每个子集，我们将对数组元素的初始贡献求和，并添加所选索引的贡献。 这立即变得不可行，因为每个测试用例有 2^n 个子集，即使 n = 40 这也已经变得太大，而这里 n 达到 100000。 

关键的观察结果是，该操作干净地分解为 2 的指数的加法贡献。 我们不跟踪实际值，而是只跟踪产品中存在两个因子的数量。 每个数组元素贡献一个固定量，等于该数字中 2 的指数。 每次我们选择索引 i 时，我们都会将 i 中的 2 的指数相加。 

这将问题简化为选择“权重”为 v2(i) 的指数子集，旨在达到所需的总赤字。 由于每个指标最多只能使用一次，因此问题就变成了选择具有固定权重的项目以达到项目数量最少的目标。 这自然可以通过首先采用最大 v2(i) 的索引来解决，因为每个操作的成本相同，但提供不同的收益。 

我们还依赖于这样一个事实：v2(i) 很小，以 O(log n) 为界，因此按指数对索引进行分组可以实现有效的计数策略。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | v2(i) 桶的贪婪 | O(n) | O(n) | 已接受 |

## 算法演练

 我们将问题重写为乘积中两个的跟踪能力。 令初始贡献为所有元素的 v2(ai) 之和。 我们需要至少达到 n。 对索引 i 的每个操作都会添加 v2(i)。 

1. 通过对所有元素求和 v2(ai) 来计算数组乘积中 2 因数的初始总数。 这就是我们预算的起点。 
2. 计算需要多少个附加因子。 如果当前总数已经达到或超过n，则答案立即为零，因为不需要任何操作。 
3. 如果存在赤字，则将 D 定义为 n 减去当前总数。 这是我们必须从所选指数中获得的额外的 2 次方的确切数量。 
4. 对于从 1 到 n 的每个索引 i，计算 v2(i)。 按此值对索引进行分组，因为具有相同 v2(i) 的所有索引在贡献方面可以互换。 
5. 按 v2(i) 的降序考虑这些组。 在移动到下一组之前，始终从最高组中获取尽可能多的索引。 每个选定的索引都会将剩余赤字减少 v2(i)，并将操作计数增加 1。 
6. 一旦赤字变为非正值，就立即停止。 所选索引的数量就是答案。 
7. 如果使用所有指数后赤字仍然为正，则输出 -1，因为即使所有操作的最大可能贡献也不够。 

为什么它有效是基于单调交换论证。 所有操作的成本相同，因此唯一重要的因素是每次操作减少赤字的程度。 由于 v2(i) 值是独立且固定的，因此选择任何较低贡献的索引而不是较高贡献的索引只会增加所需的操作数量。 因此，按 v2(i) 排序并贪婪地获取是最佳的。 分组结构确保我们不需要显式排序； 我们只汇总每个指数的计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def v2(x):
    return (x & -x).bit_length() - 1 if x else 0

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    base = 0
    for x in a:
        base += (x & -x).bit_length() - 1 if x else 0

    need = n - base
    if need <= 0:
        return 0

    cnt = [0] * (n + 1)
    for i in range(1, n + 1):
        cnt[(i & -i).bit_length() - 1] += 1

    ans = 0
    for w in range(n, -1, -1):
        if need <= 0:
            break
        take = min(cnt[w], (need + w - 1) // w if w > 0 else cnt[w])
        if w == 0:
            continue
        use = min(cnt[w], (need + w - 1) // w)
        need -= use * w
        ans += use

    if need > 0:
        return -1
    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        out.append(str(solve()))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该解决方案首先计算整个乘积中 2 的初始指数，这只是数组上位估值的总和。 然后，它计算赤字并建立一个频率表，其中有多少个指数贡献每个可能的指数。 

关键的实现细节是避免排序。 相反，我们直接计算每个 v2(i) 有多少个索引，因为对于典型约束，值的范围最多约为 17。 然后我们首先贪婪地消耗更高的权重。 

处理零重量时必须小心。 v2(i) = 0 的指数根本无助于减少赤字，因此除非问题结构需要对它们进行计数（但事实并非如此），否则它们会被忽略。

 ## 边缘情况

 一种边缘情况是数组已经满足要求。 该算法通过计算非正赤字并在任何索引处理之前返回零来立即处理此问题。 

另一种边缘情况是许多索引的 v2(i) 等于 0。 这些指数无助于减少赤字，因此可以安全地忽略它们，而不会影响正确性。 该算法永远不会错误地使用它们，因为它们没有提供任何好处。 

最后的边缘情况是即使使用所有索引也无法达到所需的指数。 在这种情况下，所有 v2(i) 的累加总和不足，贪婪过程耗尽了所有有用的索引，而赤字仍然为正，正确地导致 -1。
