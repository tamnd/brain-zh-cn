 ## 解决方案
 ## 问题理解

 我们给出了一个月，其中某一特定日期的工作日是已知的。 该已知锚由 1 到 31 之间的日期数字和工作日名称（例如星期一或星期日）组成。 使用这个锚点，我们必须确定同月中另一天的工作日。 

该问题的结构本质上是一个线性日历：每天将工作日向前推进一步，以七为一个周期。 两个日期之间的向前或向后移动仅取决于它们的天数差异，而不取决于任何特定于月份的怪癖，例如不同的长度或闰年。 我们唯一需要的操作是将数字偏移量转换为长度为 7 的循环序列中的移位。 

约束非常小，天数以 31 为界。这立即排除了对复杂预处理、大范围模拟或数据结构的任何需要。 任何计算两个整数之间的差并应用模运算的解决方案在恒定时间内就已经足够了。 

主要的边缘情况源于工作日周期中的环绕行为。 例如，如果已知日期接近周末，而目标日期在该月早些时候，则偏移变为负值。 忘记标准化模 7 的简单实现可能会产生不正确的索引，甚至负数组访问。 另一个微妙的问题是工作日订购的一致性。 如果工作日名称和索引之间的映射在编码和解码之间不一致，则结果将错误地移动固定偏移量。 

## 方法

 强力解释将从已知日期开始逐日模拟。 我们将已知的工作日分配给 a 天，然后向前或向后迭代直到 b 的所有天，每次增加或减少工作日。 这是可行的，因为每个步骤都是确定性的，但在最坏的情况下，我们会在整个月的长度内移动，最多 31 个步骤。 虽然这仍然是微不足道的，但从概念上讲，它是不必要的开销，并且如果边界更大，它就会变得脆弱。 

关键的观察是工作日形成一个大小为 7 的周期。 我们不需要模拟每个中间日，只需要 b 和 a 之间的净位移。 这个位移就是 (b − a)，工作日移位就是该值模 7。一旦我们将工作日转换为整数，答案就变成了一个算术表达式。 

这将整个问题简化为恒定时间映射和模块化算术，完全消除了任何迭代。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O( | b − a | ) |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们通过将工作日转换为循环数字系统并应用移位来解决该问题。 

1. 从星期一开始，按时间顺序为每个工作日指定一个 0 到 6 之间的数字。 这创建了一周的一致循环表示。 
2. 读取已知的锚日a 及其工作日s，并将s 转换为其数字形式cur。 
3. 读取目标日期 b． 
4. 计算差值 diff = b − a，它表示我们向前移动了多少天（如果为负则向后移动了多少天）。 
5. 使用 diff mod 7 将此差异转换为工作日班次，确保其始终位于 0 到 6 的范围内。 
6. 将这个偏移添加到 cur 中，并再次取模 7 以保持在工作日循环内。 
7. 将结果数字转换回工作日字符串并输出。 

### 为什么它有效

工作日系统是长度为七的纯模块化循环。 每增加一个日历日就相当于在工作日空间中加 1 模 7。 因此，从 a 天移动到 b 天正好对应于应用 (b − a) 这样的增量。 以 7 为模减少此位移可以保留班次的等价类，因此任何 7 天的完整周期都会抵消，而不会影响最后一个工作日。 字符串和索引之间的映射是双射的，因此在任何阶段都不会引入歧义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

days = {
    "Monday": 0,
    "Tuesday": 1,
    "Wednesday": 2,
    "Thursday": 3,
    "Friday": 4,
    "Saturday": 5,
    "Sunday": 6
}

rev = {v: k for k, v in days.items()}

def solve():
    parts = input().split()
    a = int(parts[0])
    s = parts[1].strip()

    b = int(input().strip())

    cur = days[s]
    shift = (b - a) % 7
    ans = (cur + shift) % 7

    print(rev[ans])

if __name__ == "__main__":
    solve()
```该解决方案首先在工作日名称和整数之间构建固定的双射，这对于执行算术至关重要。 输入分两步进行解析，因为第一行同时包含数字和字符串。 移位计算使用模 7 来确保周周期内向前和向后移动的正确性。 最后转换回字符串就完成了映射。 

一个常见的实施错误是忘记标准化负差异。 在 Python 中，负模仍然可以正确运行，但在其他语言中，除非明确调整，否则这可能会导致不正确的索引。

 ## 边缘情况

 一种边缘情况是当 b 小于 a 时，产生负差。 例如：

 输入：```
10 Friday
8
```此处，星期五对应于索引 4。差异为 8 − 10 = −2。 对 7 求模得到 5，所以我们从周五向前推进五步：

 周五 (4) → 周六 (5) → 周日 (6) → 周一 (0) → 周二 (1) → 周三 (2)

 输出是 Wednesday，它与直接向后计数匹配。 

另一种情况是当差值恰好是 7 的倍数时：

 输入：```
15 Sunday
29
```差值为 14，且 14 mod 7 = 0。工作日保持不变。 这证实了整周周期完全抵消，无论经过多少周，都会保留锚定工作日。
