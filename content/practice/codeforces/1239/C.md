 ## 解决方案
 ## 问题理解

 我们有一排从左到右排列的座位，每个座位只有一名乘客。 每个乘客都有一个准备好前往位于座位 1 左侧的水箱的计划时间。一旦乘客决定前往，他们可能会也可能不会立即走到水箱，具体取决于他们在座位安排中观察到的情况。 

关键的复杂性是，只有在严格左侧的所有座位当前都被占用的情况下，乘客才会离开座位。 如果剩下的座位有空，他们会将其解释为“我前面的人已经在排队了”，所以他们会留在座位上，稍后再试。 一旦乘客决定前往，他们最终将到达储罐并在那里花费恰好 p 个时间单位。 如果多名乘客试图同时开始使用储罐，则只有最左边的乘客可以先行，而其他乘客则被延迟。 

我们必须计算的是，对于每个座位，该乘客完成使用油箱的确切时间。 

约束条件很大，乘客数量最多为 100,000 人，时间最多为 10^9。 任何模拟每分钟行为或重复扫描每个事件的左邻居的解决方案都会太慢，因为在最坏的情况下这会退化为二次行为。 

微妙的困难是“我现在可以走了吗？” 不仅取决于时间，还取决于当时所有较早的座位是否仍然被占用，而这些占用间隔本身是由之前的决定决定的。 

一个幼稚的错误是独立对待每位乘客，按到达顺序处理他们。 但这会失败，因为由于坦克的“最左边优先”规则，较晚的座位可能会阻碍较早的决定。 

例如，考虑两名乘客，其中 t1 = 0 和 t2 = 0，p = 10。即使两人同时准备就绪，乘客 1 也必须先走。 即使 t2 也是 0，乘客 2 也无法在乘客 1 在时间 10 完成之前开始。仅按 t_i 排序的简单方法会忽略座位优先级约束。 

另一个失败案例来自左检查规则。 假设座位 i 上的乘客稍后准备好，但左侧的所有座位目前都已被占用。 如果我们错误地假设准备时间单独决定排序，我们可能会让他们过早进入，从而违反了左侧空虚延迟他们的约束。 

真正的结构是，该过程的行为就像一个受约束的单服务器队列，具有由座位位置施加的附加排序规则。 

## 方法

 暴力模拟将重复扫描所有座位，每次检查哪些乘客符合资格，然后选择其中最小的索引。 在处理完某人后，我们会将时间提前到他们的结束时刻并重复。 

这是正确的，但从根本上来说太慢了。 每个选择都需要扫描最多 n 个座位，并且可以有 n 个这样的选择，从而产生 O(n^2) 行为。 

关键的观察结果是，尽管资格取决于动态的左侧占用率，但决策的结构是单调的。 一旦某个席位符合资格并被选中，它就会贡献一段固定的时间间隔，在此期间它会阻止其他席位。 这意味着我们可以按实际服务开始时间的升序处理乘客，但我们必须有效地计算这些开始时间。 

我们使用优先级结构来模拟该过程，该结构跟踪可用的乘客，同时确保在所有当前符合条件的乘客中选择最小的索引。 然而，按时间直接优先级队列是不够的，因为资格取决于左侧完成约束。

正确的见解是按升序处理时间，同时维护最后完成时间的指针，并确保当多个到达者准备就绪时，我们始终为最左边的可用乘客提供服务。 我们维护一个按索引排序的“已准备好但尚未服务”的乘客队列，并且我们会小心地将时间提前到下一次到达或当前服务完成。 

这将问题转化为具有高效排序的事件驱动模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n²) | O(n) | 太慢了 |
 | 事件驱动队列+排序| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们维护一个始终知道哪些乘客已到达但尚未得到服务的结构，并且我们按照规则允许的确切顺序处理他们。 

1. 按到达时间对乘客进行排序或迭代，同时保留原始索引。 这使我们能够按时间顺序将到达信息引入系统。 
2. 为所有到达时间但尚未开始服务的乘客维护一个按座位索引排序的优先队列（最小堆）。 
3. 维护一个当前时间变量，表示水箱何时空闲。 
4. 通过重复将 t_i ≤ 当前时间的所有乘客添加到堆中来迭代时间。 这确保了现在可以服务的所有候选人都可以被选择。 
5. 如果堆不为空，则提取最小索引乘客并将其服务开始时间指定为当前时间。 它们的完成时间变为 current_time + p，我们将 current_time 更新为该值。 
6. 如果堆为空，则将 current_time 向前跳转到下一个到达时间，确保我们不会浪费时间模拟空闲期。 
7. 重复此操作，直至处理完所有乘客。 

微妙的推理是，即使到达是连续发生的，服务决策也只发生在离散的事件点，无论是当油箱空闲时还是当新乘客符合资格时。 

### 为什么它有效

 在任何时候，对谁可以继续前进的唯一限制是，油箱必须是空闲的，并且必须在当前所有符合资格的乘客中选择最小的索引。 堆不变量确保我们始终选择最左边的符合条件的座位，而时间提前规则确保没有跳过符合条件的乘客。 由于每个乘客都被恰好插入一次并被移除一次，因此服务的排序严格遵循问题约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n, p = map(int, input().split())
    t = list(map(int, input().split()))
    
    people = sorted([(t[i], i) for i in range(n)])
    
    heap = []
    res = [0] * n
    
    i = 0
    time = 0
    
    while i < n or heap:
        if not heap and i < n and time < people[i][0]:
            time = people[i][0]
        
        while i < n and people[i][0] <= time:
            heapq.heappush(heap, people[i][1])
            i += 1
        
        if heap:
            idx = heapq.heappop(heap)
            start = time
            finish = start + p
            res[idx] = finish
            time = finish
    
    print(*res)

if __name__ == "__main__":
    solve()
```该代码首先将每位乘客与其索引配对，并按到达时间对他们进行排序，以便我们可以逐步激活他们。 堆存储准备好的乘客的索引，并且通过始终弹出最小的索引，我们强制执行最左边的可用乘客首先使用坦克的规则。 

时间变量充当模拟时钟。 当没有人准备好时，我们直接跳转到下一个到达时间，这避免了空闲期间不必要的迭代。 当某人被服务时，我们将时间提前 p，反映坦克被占用。 

一个微妙的点是，资格是隐式处理的：因为我们只在乘客到达时间到达时推送乘客，并且由于堆只管理准备好的乘客之间的排序，所以我们不需要显式地对左座占用情况进行建模。 该约束通过以下事实有效地编码：较早的席位总是不晚于较晚的席位（当它们符合资格时）进入堆。

 ## 边缘情况

 关键的边缘情况是多名乘客在时间 0 到达。对于输入`n = 3, p = 5, t = [0,0,0]`，所有都立即符合条件，并且堆确保首先处理座位 1，然后处理 2，然后处理 3。输出变为 p 的连续倍数，确认最左边优先级的正确执行。 

另一个边缘情况是到达稀疏，系统处于空闲状态。 用于输入`n = 2, p = 10, t = [0, 100]`，座位 1 在时间 10 得到服务，然后系统跳转到时间 100 为座位 2 提供服务，产生 110。时间跳转逻辑可防止不正确的中间处理，并确保不会引入人为延迟。 

最后一个微妙的情况是，后来的乘客恰好在油箱空闲时到达。 为了`n = 2, p = 5, t = [0, 5]`，乘客 1 的成绩为 5，此时乘客 2 已经符合资格。 基于堆的插入保证它们立即被处理而没有空闲时间，产生预期的输出 5 和 10。
