 ## 解决方案
 ## 问题理解

 我们有两个整数。 一种是固定的类基参数$k$，另一个是上限$r$。 对于任意非负整数$n$，我们定义一个过程：如果$n$可以整除$k$，我们将其除以$k$，否则我们减去 1。重复此操作直到达到 0 给出了一些操作$f(n)$。 任务是最大化$f(n)$在所有整数上$n$在范围内$[0, r]$。 

关键的难点不是计算$f(n)$对于单个值。 一旦我们注意到该过程的行为类似于重复删除基数中的最后一位数字，该部分就会变得结构化$k$。 真正的挑战是搜索所有值直到$r$，它可能非常大，因此我们需要推理数字结构如何影响成本，而不需要模拟每个$n$。 

问题设置隐含的约束是典型的竞争性编程限制：$r$足够大以至于不可能迭代所有值，因此任何评估每个值的解决方案$n$独立地是二次或线性的$r$，这太慢了。 我们需要一些更接近对数的东西，或者在最坏的情况下是线性的位数。 

出现微妙的边缘情况时$n$基础结构发生重大变化$k$。 例如，当最高有效位在递减后变为零时，位数实际上会减少。 另一个问题是较小的值$n$，其中“数字公式”仍然成立，但当表示只有一位数字时需要仔细解释。 

## 方法

 天真的方法很简单。 对于每一个$n \le r$，模拟该过程：如果能被整除$k$，除，否则减一，计算步数。 每次模拟费用$O(\log_k n)$，因为每次除法都会减小幅度，但在最坏的情况下，我们会在除法发生之前进行多次减法。 全面的$n$，这导致大约$O(r \log r)$，这远远超出了可行的限制$r$很大。 

转折点是意识到这个过程相当于在基地工作$k$。 每次减法都会减少最后一位数字，每次除法都会删除一位数字。 这意味着步数与数字结构直接相关$n$在基地$k$。 事实上，每个数字都贡献了它的价值加上结构成本，从而形成了一个干净的封闭形式：$$f(n) = (\text{sum of digits of } n \text{ in base } k) + (\text{number of digits}) - 1$$因此，我们不是模拟转换，而是最大化基于数字的函数。 

现在问题变成：在所有数字中$n \le r$，最大化仅依赖于基数中的数字的函数$k$。 这是一个经典的数字 DP 式结构，但我们不需要完整的 DP。 我们只需要最大值，并且每个数字的目标都是单调的：更大的数字总是有帮助的。 

这允许对前缀进行贪婪构造$r$在基地$k$。 我们修复匹配的前缀长度$r$，然后在我们低于的第一个位置$r$，我们将该数字减一位并用$k-1$，最大化数字和，同时保持低于$r$。 

我们还处理选择零公共前缀的特殊情况，如果前导数字允许，这会有效地将位数减少一位。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟|$O(r \log r)$|$O(1)$| 太慢了|
 | Base-k 数字贪婪构造 |$O(\log_k r)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 转换$r$进入其基地$k$表示。 这给出了一个数字数组，其中每个位置对应于$k$。 这是必要的，因为目标函数是基于数字的。 
2.对于每个可能的前缀长度$p$从$0$到中的位数$r$，假设我们匹配第一个$p$的数字$r$。 这固定了候选编号的最高结构。 
3.如果$p$等于全长，候选者恰好是$r$，因此它的值是直接根据数字总和加上数字计数计算得出的。 
4. 否则，在位置$p$，我们减少数字$r$加 1，前提是它不为零。 如果它为零，则此前缀选择无效，因为我们无法在不提前减少长度的情况下形成较小的数字。 
5. 减少该数字后，将所有剩余位置填入$k-1$。 这最大化了数字和，同时保证构造的数字严格小于$r$。 
6.如果我们选择$p = 0$，我们正在有效地构建位数少于$r$。 在这种情况下，最好的可能数字是所有数字都等于$k-1$少一位数字$r$，因为这会在约束下最大化数字总和和数字计数。 
7. 计算每个候选人的目标值并取最大值。 

### 为什么它有效

 任意数量$n \le r$必须匹配$r$在某些前缀中，第一个不同的数字有所不同。 在该位置，它必须严格小于，并且所有后面的数字都可以自由选择，直到$k-1$。 由于目标在每个数字上严格增加，并且随着数字计数的增加而增加，因此任何最佳解决方案都必须在第一个偏差之后最大化数字，并尽可能延迟偏差。 这迫使贪婪结构超越前缀，确保这些构造形式之外的候选者都无法改善目标。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def to_base_k(x, k):
    if x == 0:
        return [0]
    digs = []
    while x > 0:
        digs.append(x % k)
        x //= k
    return digs[::-1]

def value(digits):
    # (sum of digits) + (number of digits) - 1
    return sum(digits) + len(digits) - 1

def solve():
    k, r = map(int, input().split())

    digits = to_base_k(r, k)
    n = len(digits)

    best = 0

    # case: use r itself
    best = max(best, value(digits))

    # try prefix matches
    for p in range(n):
        if digits[p] == 0:
            continue

        cand = digits[:p]
        cand.append(digits[p] - 1)
        cand.extend([k - 1] * (n - p - 1))

        best = max(best, value(cand))

    # try shorter length (p = 0 type case)
    if n > 1:
        cand = [k - 1] * (n - 1)
        best = max(best, value(cand))

    print(best)

if __name__ == "__main__":
    solve()
```转换为基数$k$至关重要，因为它将减法和除法过程转化为数字问题。 帮手`value`直接对推导公式进行编码，避免任何模拟。 

主循环枚举我们中断的第一个位置$r$。 条件`digits[p] == 0`跳过无效的情况，在这种情况下，我们无法在不提前借用的情况下减少该数字。 一旦我们减少了一个数字，用以下内容填充后缀$k-1$保证剩余职位的最大贡献。 

最后一个特殊情况处理位数少于$r$，我们通过使用 all 独立地最大化数字计数和数字总和$k-1$数字。 

## 工作示例

 ### 示例 1

 让$k = 10$,$r = 274$。 以 10 为基数的数字是$[2, 7, 4]$。 

| 前缀 p | 候选数字| 价值|
 | ---| ---| ---|
 | 3 | [2,7,4]| 2+7+4+3-1 = 15 |
 | 0 | [9, 9] | 9+9+2-1 = 19 |
 | 1 | [1,9,9]| 1+9+9+3-1 = 21 |
 | 2 | [2,6,9]| 2+6+9+3-1 = 19 |

 最好的是前缀 1，给出 21。这说明了为什么更早地推动偏差有时会占主导地位，因为数字计数和后缀最大化是相互作用的。 

### 示例 2

 让$k = 9$,$r = 413089$。 数字是$[4,1,3,0,8,9]$。 

| 前缀 p | 候选数字| 价值|
 | ---| ---| ---|
 | 6 | [4,1,3,0,8,9] | 固定|
 | 2 | [4,1,2,8,8,8] | 最佳候选人 |
 | 3 | 无效（数字 0） | 跳过|
 | 0 | [8,8,8,8,8] | 较短长度的外壳 |

 这表明跳过零数字是多么必要，因为在不提前借用的情况下减少零是不可能的。

 ## 边缘情况

 一个关键的边缘情况是当$r$是一个幂$k$， 例如$1000_k$。 朴素的前缀减少可能会太晚尝试减少零数字，这是无效的。 该算法正确地跳过此类前缀，而是依赖于较早的位置或较短长度的结构。 

另一个边缘情况是$r < k$，其中基本表示有一个数字。 在这种情况下，仅存在两个候选者：$r$本身和$k-1$。 该算法自然地涵盖了两者，因为前缀循环没有任何意义，并且较短长度的情况要么不存在，要么适当占主导地位，无需特殊的大小写即可产生正确的结果。
