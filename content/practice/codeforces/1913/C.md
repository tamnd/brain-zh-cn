 ## 解决方案
 ## 问题理解

 我们正在维护两个权力的动态集合。 每次我们收到 ADD 操作时，我们都会插入一个以下形式的值$2^x$进入多重集合。 每个 GET 操作都会提出一个可达性问题：我们能否选择当前可用数字的某个子集，其总和等于目标$w$。 

关键特征是每个元素都是 2 的纯幂，并且允许重复，因为多重集可以包含相同幂的重复插入。 这将结构变成了接近二进制表示系统的东西，但有一点不同，我们可能有多个相同价值的“硬币”。 

这些限制迫使我们处理最多$10^5$在线操作。 每个 GET 查询可能涉及最多一个目标$10^9$，所以我们不能尝试所有子集，甚至不能进行每个查询的指数推理。 任何尝试枚举子集或针对每个查询运行背包式 DP 的解决方案都将立即失败，因为$2^{30}$每个查询的子集组合已经远远超出了限制。 

当多个相同的力量累积时，就会出现一个微妙的问题。 例如，如果我们插入三个$2^0$元素，我们可以仅使用这些元素来形成像 1、2 或 3 这样的和。 独立处理每个幂而不考虑计数的幼稚方法在这里会失败。 正确的解释是，每个指数的行为就像有限数量的相同硬币，并且位之间的进位成为可能。 

另一个失败案例是使用新的贪婪分解独立处理每个 GET，但忘记了之前的 ADD 操作会累积状态。 由于多重集的发展，每个查询从头开始重新计算也会太慢。 

## 方法

 暴力解释很简单：对于每个 GET 查询，考虑多重集的所有子集并检查是否有任何子集总和为$w$。 如果有$k$当前在多重集中的元素，这需要检查$2^k$子集，呈指数增长。 即使是为了$k = 40$，这变得不可行，而这里$k$可以达到$10^5$。 

第二个简单的改进是通过动态编程集维护所有子集和。 每次 ADD 之后，我们通过将新的幂添加到所有现有的和中来合并新的和。 在最坏的情况下，这仍然使每次插入可达到的总和数量增加一倍，再次导致指数增长。 

关键的观察是所有值都是 2 的幂。 这意味着每个数字都对应一个二进制位置，并且将它们组合起来的行为就像带有可能进位的二进制加法一样。 我们不需要跟踪子集，而只需要跟踪每个指数存在多少个副本。 

让$c[i]$元素数量等于$2^i$。 回答我们是否可以组建$w$，我们尝试解释$w$在二进制中，贪婪地从最低到最高匹配位，使用可用计数并向上携带剩余。 这将问题简化为二进制权重的有界硬币系统，其中贪婪进位传播是有效的，因为每个权重恰好是前一个权重的两倍。 

这会将每个 GET 查询转换为最多 31 位的小循环。

 | 最佳 |$O(30)$每个查询|$O(30)$| 已接受 |

 ## 算法演练

 我们维护一个数组`cnt`在哪里`cnt[i]`存储多少次$2^i$已插入。 

1. 对于ADD$x$, 增量`cnt[x]`一个。 这直接记录了该电源的可用性。 
2. 对于 GET$w$、模拟建筑$w$一点一点地从最低功率到最高功率。 
3. 对于每个位位置$i$，计算我们当前是否需要一个单位$2^i$从$w$。 
4.添加可用币种`cnt[i]`到该水平的运行“供应”。 该供应量代表了多少单位$2^i$我们可以使用。 
5. 如果当前位$w$是1，我们必须消耗一单位$2^i$。 如果供应量为零，则答案立即为“否”，因为我们无法满足这一点。 
6.满足要求后，剩余供应量$i$向上进行为$2^{i+1}$，从两$2^i$可以组成一个$2^{i+1}$。 
7. 继续此过程直至最大位$w$，最后检查剩余进位是否无关或可以吸收。 

关键的想法是我们永远不会丢弃多余的东西； 一切都向上传播，就像带有资源池的二进制加法一样。 

### 为什么它有效

 在每一位位置$i$，对该价值的所有贡献都是无法区分的：它们都是$2^i$。 任何配对或剩余部分都会自然地转换为下一位，因为$2 \cdot 2^i = 2^{i+1}$。 这强制执行严格的层次结构，其中较低位的决策完全确定可行性而无需回溯。 每一位的贪婪消耗是安全的，因为无法满足所需的位不能通过更高位来修复，而剩余的总是可以通过进位最佳地重用。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    m = int(input())
    cnt = [0] * 31

    for _ in range(m):
        t, v = map(int, input().split())

        if t == 1:
            cnt[v] += 1
        else:
            w = v
            carry = 0
            ok = True

            for i in range(31):
                carry += cnt[i]

                if (w >> i) & 1:
                    if carry == 0:
                        ok = False
                        break
                    carry -= 1

                carry //= 2

            if ok:
                print("YES")
            else:
                print("NO")

if __name__ == "__main__":
    solve()
```该实现保留了大小为 31 的固定频率数组，因为$2^{30}$足以覆盖所有值$10^9$。 每个 GET 查询都使用运行进位来模拟目标的二进制构造。 

关键细节是按升序处理位。 在每个级别之后，进位必须始终除以二，以反映聚合到下一个 2 的幂。 未能正确应用这种划分会导致更高级别的资源过多计算。

 ## 边缘情况

 当许多小功率累积并且必须通过多个进位级联时，就会出现一种边缘情况。 例如，插入八个副本$2^0$应该立即表现得像一个单身$2^3$。 该算法处理这个问题是因为每个级别都执行整数除以二，重复向上传播剩余直到稳定。 

另一种情况是 GET 查询请求的值大于任何单个存储的指数。 即使不存在单一的匹配能力，组合仍然可以发挥作用。 例如，两个$2^3$条目可以满足$2^4$。 进位机制确保在评估较高位之前始终考虑这些合并，因此算法永远不会错误地拒绝有效的构造。
