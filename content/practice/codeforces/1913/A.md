 ## 解决方案
 ## 问题理解

 我们得到一串数字，代表两个连接的整数，即原始评级`a`以及增加的评级`b`，但它们之间没有明显的分离。 我们的任务是将这个字符串分成两个数字，使得两个数字都是严格正数，都没有前导零，并且`b`严格大于`a`。 如果多个分割满足这些条件，我们可以返回任何一个； 如果不存在有效的分割，我们返回`-1`。 

每个测试用例的输入大小都很小：字符串的长度在 2 到 8 之间。我们最多可能有 10,000 个测试用例。 由于每个字符串最多 8 个字符，因此任何检查所有可能拆分的方法都是可行的，因为对于单个字符串最多有 7 个拆分位置。 关键的挑战是处理前导零、相等的数字以及强制执行`b > a`正确。 例如，给定输入`200200`，粗心的实现可能会将其分割为`200`和`200`，失败是因为`b`并不严格大于`a`。 同样，分裂`1001`作为`10`和`01`无效，因为`01`有一个前导零。 

## 方法

 蛮力方法很简单。 对于每个字符串，尝试每个可能的位置将其拆分为两个非空部分。 将两个部分都转换为整数并检查它们是否满足条件：都没有前导零，都大于零，并且`b > a`。 由于字符串的长度最多为 8，因此每个测试用例最多需要 7 次检查。 对于 10,000 个测试用例，最多会产生 70,000 个检查，这在实践中是可以接受的。 暴力方法之所以有效，是因为保证检查每个可能的有效分割。 

一个观察简化了我们的工作：如果一个字符串有长度`n`，尝试靠近中间的分割通常会产生更小的结果`a`和更大的`b`，这使得`b > a`更有可能。 然而，为了正确性，我们仍然需要在最坏的情况下检查所有分割，因为有效的分割可能发生在任何位置，特别是对于数字重复或增加的字符串。 

在这种情况下，最佳方法仍然是提前停止的强力方法：从左到右迭代所有分割位置并返回第一个有效分割。 由于输入限制，操作数量仍然很小，这保证了正确性，而没有不必要的复杂性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解/提前停止| O(n * t)，n ≤ 8，t ≤ 10^4 | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，读取连接的字符串`s`。 
3. 迭代可能的分割位置`i`从 1 到`len(s)-1`。 分裂分裂`s`进入`a_str = s[:i]`和`b_str = s[i:]`。 
4. 检查前导零：if`a_str`或者`b_str`开始于`'0'`，跳过这个分割。 
5. 转换`a_str`和`b_str`为整数`a`和`b`。 
6. 检查两个数字是否严格为正数（`a > 0`和`b > 0`）并且如果`b > a`。 如果是这样，则打印`a`和`b`并停止处理该字符串。 
7. 如果检查完所有位置后没有找到有效的分割，则打印`-1`。 

为什么有效：该算法检查将字符串分成两个数字的所有可能方法。 通过明确拒绝带有前导零的分割并强制执行`b > a`，它保证任何输出都满足问题约束。 早期停止确保一旦找到有效的分割，我们就能有效地产生结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    n = len(s)
    found = False
    for i in range(1, n):
        a_str, b_str = s[:i], s[i:]
        if a_str[0] == '0' or b_str[0] == '0':
            continue
        a, b = int(a_str), int(b_str)
        if b > a:
            print(a, b)
            found = True
            break
    if not found:
        print(-1)
```该解决方案使用有效地读取输入`sys.stdin.readline`。 我们迭代所有分割点并检查每个候选分割点。 首先过滤前导零以避免不必要的整数转换。 提前停止确保我们返回第一个有效的分割而无需额外的工作。
