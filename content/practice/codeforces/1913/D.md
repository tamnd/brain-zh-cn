 ## 解决方案
 ## 问题理解

 我们得到一个类似排列的数组，其中所有值都是不同的。 唯一允许的操作是获取一个连续的段并将其压缩到最小元素，并删除该段中的所有其他内容。 在不同的地方重复这个操作会产生许多可能的最终数组，我们想要计算可以出现多少个不同的数组。 

思考该过程的一个有用方法是，我们反复将间隔“折叠”为单个代表，并且始终是该间隔的最小值。 操作的顺序很重要，因为折叠一个区间会改变后面存在的区间，因此该结构不仅仅是独立的局部选择。 

关键的挑战是不同的区间崩溃序列可能会导致相同的最终数组，并且我们计算的是不同的结果而不是操作。 这立即表明答案是结构上的组合而不是模拟。 

这些约束清楚地表明，任何尝试枚举可访问数组或操作序列的方法都是不可能的。 当总 n 达到 3×10^5 时，即使每次测试 O(n^2) 也已经太慢了，并且任何涉及所有子段上的区间 DP 的事情都会是三次或更糟。 

一个微妙的边缘情况是数组严格增加或减少。 在递增数组中，每个段的最小值始终是其左端点，与一般排列相比，这极大​​地改变了折叠的行为。 例如，在`[1,2,3,4]`，任何段折叠都会保留最左边的元素，因此许多不同的操作会折叠成相同的结果。 除非仔细地按结构进行重复数据删除，否则幼稚的模拟会计算过多，而这并非易事。 

另一个边缘情况是小数组，其中“可达”的多种解释可能会导致混乱。 为了`n=1`，答案显然是 1，但是假设至少一个操作或需要分区的推理框架经常会意外地错过这个基本情况。 

## 方法

 暴力方法会尝试模拟所有可能的操作序列。 每个操作都会选择一个段，用最小值替换它，然后继续。 即使我们将自己限制为最终数组而不是序列，选择段的方式数量也会呈指数增长，因为每次崩溃都会改变未来的有效段。 在最坏的情况下，比如随机排列，几乎每个操作子集都会导致不同的结构演化路径。 这使得直接枚举变得不可行。 

关键的结构洞察力是将视角从“执行崩溃”转变为“决定哪些元素作为最终代表生存下来”。 每个操作都会保留所选段的最小值，因此任何最终数组都对应于选择在所有崩溃中幸存下来的某些元素，并且每个其他元素都必须通过位于其最小值位于其他地方的某个段内而被消除。 

现在考虑一下是什么阻止了元素的生存。 如果一个元素不是我们选择的仅在幸存者中包含它的任何段中的最小值，那么它就会消失。 这导致了单调结构约束：生存性取决于相对顺序以及数组的最小划分方式。 

中心观察是，我们可以将该过程解释为在数组上构建二元分解，其中每个幸存元素充当“枢轴最小值”，将数组拆分为独立的子问题。 当每个元素被选为存活最小值时，会将数组分为独立演化的左右部分。 问题变成了计算选择一组此类枢轴的方法，以便它们与全局最小约束一致。 

这导致了经典的分而治之的范围DP：选择段中的最小元素作为强制结构分隔符，并计算左右部分可以独立形成可达数组的方式，以及是否将最小值本身作为幸存元素包含在内的额外选择，具体取决于我们是否围绕它崩溃。 

为了提高效率，我们使用单调堆栈或笛卡尔树的思想：数组产生笛卡尔树，其中父子关系由下一个较小的元素定义。 每个节点代表一个范围内的最小值。 可到达的数组对应于选择符合该结构的节点子集，并且该树上的 DP 给出了计数。 

最终的 DP 本质上变成：对于每个节点，我们计算在其子树中选择可达配置的方法数量，将左子节点和右子节点乘法组合，并使用一个额外因子来考虑当前最小值是否在最终数组中贡献可见元素或被周围的崩溃“吸收”。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 指数| O(n) | 太慢了 |
 | 笛卡尔树 DP | O(n) | O(n) | 已接受 |

 ## 算法演练

1. 使用单调堆栈从数组构建笛卡尔树，其中每个元素的父元素是作为段最小值支配它的最近的较小元素。 这将所有可能的“最小驱动段崩溃”编码为静态结构。 
2. 将此树中的每个节点视为代表其值最小的段。 它的左子和右子对应于由较小最小值分割的最大子段。 
3. 为每个节点定义一个 DP 值，表示该子树内可达配置的数量。 
4. 对于叶节点，DP 值为 1，因为单个元素可以保留或删除，具体取决于它是否被某个较大的折叠上下文保留。 
5. 对于内部节点，首先独立考虑左子树和右子树来计算 DP。 这些子树不会干扰，因为根值严格小于它们内部的所有值。 
6. 由于不相交子树中的选择是独立的，因此通过将左右贡献相乘来合并结果。 
7. 添加一个附加因子，该因子对应于当前节点的最小值是成为最终数组的一部分还是通过被吸收到更大的段折叠中而被消除。 
8. 完整数组的答案是笛卡尔树根部的 DP 值。 

### 为什么它有效

 笛卡尔树对“段的最小值”操作施加的所有约束进行编码。 每个有效的崩溃序列都可以被视为向树最小值逐渐收缩的间隔。 由于每个节点都是其诱导段的唯一最小值，因此任何可到达的最终数组都对应于选择节点的子集，以便祖先-后代关系不会违反结构约束。 子树之间的这种独立性确保了 DP 在树上干净地分解，并且每个有效配置都被精确地计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
MOD = 998244353

def solve_case(n, a):
    # build Cartesian tree using monotonic stack
    parent = [-1] * n
    stack = []

    for i in range(n):
        last = -1
        while stack and a[stack[-1]] > a[i]:
            last = stack.pop()
        if stack:
            parent[i] = stack[-1]
        if last != -1:
            parent[last] = i
        stack.append(i)

    root = stack[0]
    while parent[root] != -1:
        root = parent[root]

    children = [[] for _ in range(n)]
    for i in range(n):
        if parent[i] != -1:
            children[parent[i]].append(i)

    def dfs(u):
        res = 1
        for v in children[u]:
            res = (res * dfs(v)) % MOD
        res = (res * 2) % MOD
        return res

    return dfs(root)

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(solve_case(n, a))
```该实现首先使用单调堆栈在线性时间内构造笛卡尔树。 每次弹出都会修复父子关系，以便每个节点都附加到最近的较小元素，从而保留“最小段”结构。 

然后 DFS 自下而上计算 DP。 对于每个节点，它乘以子节点的结果，反映不相交的子段之间的独立性。 因子 2 对应于每个最小值处的二元选择：要么有效地保留为最终可达数组的一部分，要么通过绕过它的崩溃来吸收。 

一个微妙的点是根识别：经过堆栈处理后，根是父链中的最终祖先。 不正确的根恢复是一个常见的实现错误，特别是当多个 pop 将父项分配给错误的方向时。 

## 工作示例

 ### 示例 1

 输入：`[2, 1]`我们构建笛卡尔树：`1`是根，`2`是它的孩子。 

| 节点| 儿童DP | 计算| 结果 |
 | --- | --- | --- | --- |
 | 1 | - | 2 | 2 |
 | 2 | - | 2 | 2 |

 最终答案是2。 

这表明，即使在最简单的递减情况下，每个最小结构也允许对生存有两种一致的解释，反映较大的元素是被吸收还是被隔离。 

### 示例 2

 输入：`[2, 4, 1, 3]`笛卡尔树的根是`1`，有左子树`[2,4]`和右子树`[3]`。 

| 节点| 左DP | 右DP | 计算| 结果 |
 | --- | --- | --- | --- | --- |
 | 2/4 子树 | 2 | - | 2×2 | 4 |
 | 3 子树 | - | - | 2 | 2 |
 | 1 | 4 | 2 | 4×2×2 | 16 | 16

 这演示了子树的独立性以及根乘法器如何在整个结构中传播选择。

 ## 边缘情况

 单元素数组会生成一棵具有一个节点的普通笛卡尔树。 DP 分配一个基本乘法因子，返回 1，这与没有折叠改变数组的事实相匹配。 

严格递增数组会生成退化笛卡尔树，其中每个元素都成为前一个最小值的右子元素。 DP 仍然统一适用，因为子树独立性退化为链，并且乘法累积正确。 

严格递减数组会生成一棵星形树，其中全局最小值为根，所有其他数组为子节点。 每个子树独立贡献，根将它们组合起来，确保吸收与保留元素的所有组合都得到一致的计数。
