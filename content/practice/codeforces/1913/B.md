 ## 解决方案
 ## 问题理解

 我们从一个二进制字符串开始`s`。 我们可以删除角色，每次删除支付一枚硬币，并且我们可以免费交换任何一对剩余的角色。 

经过所有操作，我们得到一个字符串`t`。 长度为`t`可以是任何来自`0`最多`|s|`，因为允许删除。 条件为`t`优秀是存在于每一个位置`t`必须与原始字符串中的相应位置不同`s`。 换句话说，对于每个索引`i ≤ |t|`，我们需要`t[i] ≠ s[i]`。 

免费掉期是问题的关键部分。 由于交换不需要任何成本并且可以任意执行多次，因此剩余字符的顺序完全在我们的控制之下。 唯一重要的是有多少`0`沙`1`删除后仍保留。 

所有测试用例的总长度最多为`2·10^5`。 这立即排除了任何尝试删除所有子集或所有可能的重新排列的解决方案。 我们需要每个测试用例接近线性时间。 由于总输入大小本身仅为`2·10^5`， 一个`O(n)`解决方案是理想的并且`O(n log n)`解决方案也很容易足够快。 

一些边缘情况很容易被忽略。 

考虑`s = "0"`。 我们可以形成的唯一非空字符串是`"0"`，并且它与原始字符串的第一个位置匹配。 唯一好的字符串是空字符串，所以答案是`1`。 

考虑`s = "01"`。 我们可以交换两个字符并得到`"10"`。 每个位置都与原来不同，所以答案是`0`。 认为每当位置最初匹配时总是需要删除的解决方案在这里会失败。 

考虑`s = "111100"`。 有四个一和两个零。 为了使前四个位置与原始位置不同，我们需要四个零，但只存在两个。 有些删减是不可避免的。 答案不是由本地交换决定的，而是由可用字符的全局计数决定的。 

这些例子暗示问题实际上在于我们是否有足够的相反位来填充每个位置。 

## 方法

 蛮力观点对于理解结构很有用。 

假设我们选择要删除的一些字符集。 之后，我们就知道还剩下多少个零和一。 由于交换是免费的，因此剩余字符的每种排列都是可以实现的。 我们可以问是否存在一个排列使得每个位置都不同于原始前缀`s`。 

暴力方法将尝试所有可能的删除数量和位置，然后测试是否存在某些有效的重排。 即使对于一个长度的字符串`n`， 有`2^n`删除选择，使得这完全不可行。 

关键的观察结果是，免费交换几乎破坏了所有位置信息。 删除后，只有剩余的 0 和 1 的数量才重要。 

假设我们想保留第一个`k`职位。 原来的前缀`s[0:k]`包含一定数量的零和一定数量的1。 

每个位置包含`0`在原始前缀中必须接收一个`1`在最后的字符串中。 每个位置包含`1`在原始前缀中必须接收一个`0`。 

让

-`need0`= 原件数量`1`前缀中的 s
 -`need1`= 原件数量`0`前缀中的 s

 这些正是我们必须放置的零和一的数量。 

现在想象一下从左到右扫描原始字符串并尝试构造最长的好前缀。 每当我们看到一个角色`c`在原始字符串中，我们需要相反字符的一个副本`1-c`来自可用字符的多集。 

如果存在这样的字符，我们就使用它。 否则，在该位置就无法进行施工。 由于后面的每个好字符串也必须满足这个位置，因此我们无法进一步扩展。 

到那时，所有剩余的字符都必须被删除。 删除的数量等于未处理的字符数。 

这给出了一个非常简单的贪心过程。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) 或更糟 | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算整个字符串中 0 和 1 的总数。 
2. 将这些计数视为可以任意重新排列的字符池。 
3. 从左到右扫描原始字符串。 
4.对于当前角色`c`，我们必须将相反的字符放在相应的位置`t`。 
5. 检查池中是否至少保留一份相反的角色。 
6. 如果存在，则消耗该相反角色的一份副本并继续。 

这意味着我们成功地又匹配了一个好字符串的位置。 
7. 如果不存在，立即停止。 

没有任何重新排列可以满足这个位置，因为每个好的字符串都需要这里相反的位。 
8.让故障发生在该位置`i`（从 0 开始）。 然后来自位置的所有字符`i`必须删除以后的内容。 
9. 答案是`n - i`。 
10. 如果扫描顺利完成，则说明每个位置都满足，无需删除。 答案是`0`。 

### 为什么它有效

 在任何位置，要求都是完全确定的：`0`原始字符串中需要一个`1`，和一个`1`需要一个`0`。 

由于交换是免费的，唯一的资源限制是还有多少个零和一个可用。 每当存在相反的字符时，使用它总是安全的，因为无论如何，每个有效的解决方案都必须为该位置花费一个相反的字符。 

如果在某个位置没有剩余相反的字符，则剩余字符的任何排列都不能满足该位置。 该长度的每个好字符串都需要一个池中根本不存在的字符。 

因此，第一个失效位置正是好弦无法延伸超过的点。 保留任何额外的字符是不可能的，因此必须删除所有剩余的字符。 删除的次数正是从失败位置开始的后缀长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    ans = []

    for _ in range(t):
        s = input().strip()
        n = len(s)

        cnt = [0, 0]
        for ch in s:
            cnt[int(ch)] += 1

        answer = 0

        for i, ch in enumerate(s):
            need = 1 - int(ch)

            if cnt[need] == 0:
                answer = n - i
                break

            cnt[need] -= 1
        else:
            answer = 0

        ans.append(str(answer))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```第一部分计算整个字符串中存在多少个零和一个。 这些计数代表任意交换后可用的字符池。 

在扫描过程中，包含的位置`0`需要一个`1`，以及一个包含的位置`1`需要一个`0`。 我们检查池中是否仍然存在相反的角色。 

如果是，我们会消耗一份副本。 从概念上讲，我们将该字符分配给最终字符串的当前位置。 

如果所需的相反位不可用，我们就到达了第一个不可能的位置。 剩下的后缀必须删除，所以答案是`n - i`。 

这`for ... else`这里施工方便。 这`else`仅当循环永不中断时才执行块，这意味着每个位置都已成功匹配，答案是`0`。 

一个微妙的点是我们永远不会从计数中删除原始字符本身。 计数代表可用于重新排列的字符多集，每次我们将一个字符分配到某个位置时，我们都会消耗该多集中的一个字符。 消耗的字符是该位置所需的相反位。

 ## 边缘情况

 ### 单字符串

 输入：```
0
```计数为`(1 zero, 0 ones)`。 第一个位置需要一个`1`，但不存在。 故障立即发生在该位置`0`。 

答案是：```
1 - 0 = 1
```算法正确返回`1`，这意味着唯一有效的结果是空字符串。 

### 所有字符相同

 输入：```
111100
```前四个位置每个都需要一个零。 整个字符串中仅存在两个零。 

消耗两个零后，所需的第三个零就不再可用。 故障发生在该位置`2`，产生答案`6 - 2 = 4`。 

该算法可以准确检测相反位的供应何时耗尽。 

### 无需删除

 输入：```
01
```计数是一零和一一。 

位置 0 消耗可用的`1`，位置 1 消耗可用的`0`。 

扫描成功完成，所以答案是`0`。 

这证实了当二进制字符串存在完全混乱时，该算法不会删除不必要的字符。
