 ## 问题理解

 任务非常直接：我们被要求生成一个纯粹由递归定义的众所周知的整数序列的开头。 该序列以两个固定种子开始，两者都等于 1，并且后面的每个值都是通过将前两个值相加而获得的。 输出要求不是参数化的，没有要处理的输入，并且我们总是准确地产生前五项。 

尽管没有明确说明约束条件，但问题的结构清楚地表明性能无关紧要。 我们只执行恒定量的算术，因此任何合理的实现都在恒定时间和恒定内存中运行。 即使是极其低效的方法仍然是可以接受的，因为序列长度是固定的。 

在通常的竞争性编程意义上，不存在有意义的边缘情况，但有一个微妙的格式限制可能会破坏解决方案：输出必须恰好包含五个由单个空格分隔的整数，并且没有尾随空格或额外的符号。 粗心的实现会在每个数字（包括最后一个数字）后打印一个空格，尽管计算出正确的值，但可能会产生错误的输出。 例如，打印`"1 1 2 3 5 "`即使数字本身是正确的，尾随空格也是无效的。 

## 方法

 强力解释是使用数组逐步模拟定义，并根据前两个值重复计算每个下一个值。 这种方法准确地反映了数学定义并且构造上是正确的。 它将建立一个列表`F`在哪里`F[0] = 1`,`F[1] = 1`，并为每个后续索引附加`F[i-1] + F[i-2]`。 

即使这种直接模拟也太过分了，因为我们只需要五个值。 算术运算的总数是恒定的，因此运行时间不依赖于任何输入大小。 进一步优化没有任何好处，因为我们已经处于尽可能最低的复杂性。 

关键的观察是斐波那契定义本质上是迭代的和局部的。 每一项仅取决于前两项，因此我们在任何时候都不需要存储超过这两个值。 这使我们能够以流方式计算序列，而无需分配数组。

 ## 算法演练

 我们迭代计算序列，同时仅保留最后两个值。 

1. 初始化代表前两个斐波那契数的两个变量，均设置为 1。它们作为递归的基本情况。 
2. 立即输出第一个值，因为它是由定义固定的。 
3. 输出第二个值，该值与第一个值相同。 
4. 重复计算下一项作为前两个存储值的总和。 计算出新值后，将存储的对向前移动，以便它们始终代表序列中的最后两项。 
5. 继续此过程，直到总共生成五个值。 

步骤 4 和 5 的关键思想是我们永远不会从头开始重新计算。 每个新值仅使用已经计算的结果将序列扩展一步，这直接反映了数学递归。 

### 为什么它有效

 在该过程中的任何时刻，两个存储的变量都代表连续的斐波那契数。 当我们计算它们的总和时，我们根据定义获得下一个斐波那契数。 通过向前移动来更新该对可以保留它们始终对应于序列中最新两项的不变性。 由于递归唯一地定义了前两项中的每一项，因此保持这个不变性可以保证每个产生的值都是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# first five Fibonacci numbers
a, b = 1, 1
out = [a, b]

for _ in range(3):
    a, b = b, a + b
    out.append(b)

sys.stdout.write(" ".join(map(str, out)))
```该解决方案使用两个基值初始化序列，然后迭代生成接下来的三个值。 该循环恰好运行了三次，因为我们已经有两个数字，总共需要五个。 

更新步骤`a, b = b, a + b`是实施的核心。 它同时向前移动窗口并计算下一个斐波那契数，而不需要临时变量。 这个顺序至关重要，因为`b`必须在旧的基础上更新`a`和`b`在覆盖任一值之前。 

最终输出使用`" ".join(...)`确保正确的间距而没有尾随空格，这是此类问题中最常见的格式陷阱。

 ## 边缘情况

 唯一有意义的边缘情况是输出格式，因为序列本身是固定的。 任何正确的计算总会产生`1 1 2 3 5`，所以失败来自于打印而不是逻辑。 

例如，一个有缺陷的实现可能会这样做：

 输入：```
(no input)
```不正确的输出：```
1 1 2 3 5
```正确输出：```
1 1 2 3 5
```算法本身从不产生尾随空格； 基于连接的输出结构确保仅在元素之间插入间距。 这使得格式约束自动满足，无需对最后一个元素进行特殊情况处理。
