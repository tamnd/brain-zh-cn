 ## 解决方案
 ## 问题理解

 我们正在使用一棵有根树，其中每个节点都存储一个整数值。 对于任意节点$x$，我们查看树的一个受限区域：的所有后代$x$其深度从$x$至多是$k$。 从这些节点中，我们将它们的值收集到一个多重集中$p(x, k)$。 因为它是一个多重集，所以重复的值很重要：如果两个不同的节点具有相同的值，则两个副本会单独出现。 

对于每个节点$x$，我们必须计算在所有无序元素对上定义的分数$p(x, k)$，包括成对的相同元素。 对于一对值$u, v$，我们取$u \oplus v$，平方，然后对所有对求和。 由于对具有多重性，这相当于对所有有序对求和$(u, v)$包括$u = v$。 

树的大小可以大到$10^5$，每个节点根据其位置贡献许多查询。 这立即排除了重新计算每个$p(x, k)$由 BFS 或 DFS 独立地进行，因为即使是线性的每节点重新计算也会导致$O(n^2)$最坏情况下的行为，例如链条。 

一个微妙的点是，分数计算的是同一多重集中的对，而不是不同节点之间的对。 如果简单的解决方案错误地对值进行重复数据删除或仅对不同的对进行计数，则会产生不正确的结果。 例如，如果$p(x, k) = \{1, 1\}$，正确的贡献包括$(1 \oplus 1)^2$两次，无论如何都是零，但在更大的情况下，重复很重要。 

另一个边缘情况是深度截止。 在链树上，靠近顶部的节点可能包括几乎所有后代，而靠近底部的节点几乎不包括任何后代。 任何假设子树大小统一的解决方案在倾斜树上都会失败。 

## 方法

 一个直接的方法是计算$p(x, k)$分别使用 BFS 或 DFS 限制深度的每个节点$k$。 对于每个节点$x$，我们将收集所有有效节点，然后计算该集合内的所有对。 如果设定的大小是$s_x$，计算分数需要$O(s_x^2)$XOR 评估，并构建设定成本$O(s_x)$。 在最坏情况的链中，根有$s_x = n$, 给予$O(n^2)$对于仅一个节点，总复杂度变为$O(n^3)$跨所有节点。 

关键的困难在于其中许多集合严重重叠。 节点及其父节点仅在树的一级上有所不同，这意味着它们的大部分贡献是共享的。 这表明重新定位或 DSU-on-tree 风格的计算重用。 

分数本身可以以允许频率计数聚合而不是显式对枚举的方式重写。 如果我们保持活动窗口中值的频率，我们可以使用每个位位置的按位贡献来表示对的总和。 对于 XOR，每个位都是独立贡献的，因此我们可以跨位分解问题并避免显式枚举对。 

这导致了我们为每个活动节点集维护每位值的计数的解决方案。 当插入或删除一个值时，我们会增量更新贡献。 结合树遍历，确保每个节点的活动区域对应于深度的滑动子树窗口$k$，我们可以有效地重用计算。 

强制执行“最大距离”的标准方法$k$” 约束是维护一个每个深度具有多个活动节点的 DFS，或者在 DFS 堆栈上维护一个滑动窗口，删除超出深度的节点$k$。 在遍历期间，每个节点的答案是根据当前活动多重集计算的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$最坏的情况|$O(n)$| 太慢了|
 | DFS+滑动窗口+比特贡献|$O(n \log A)$|$O(n + \log A)$| 已接受 |

 这里$A$是最大值（最多$10^9$）。 

## 算法演练

 我们通过从根开始的深度优先遍历来处理树，维护一个表示当前最多距离内的所有节点的结构$k$从当前节点开始。 

在 DFS 中的任何一点，我们维护一个节点窗口，其深度在$[depth[x] - k, depth[x]]$。 这可以使用按深度索引的堆栈来强制执行，其中每个深度级别存储当前活动节点的值。 

对于每个值，我们还维护活动集中的每比特计数。 这使我们能够计算 XOR 对和，而无需枚举对。 

我们维护活动集中所有对的当前全局贡献。 当我们插入一个值时，我们会更新它与现有元素形成的新对的数量。 移除时也会发生同样的情况。 

## 步骤

 1. 以节点 1 为树根，并在 DFS 遍历时计算每个节点的深度。 该深度用于以纯粹祖先的方式强制执行距离约束。 关键的观察是距离内的所有节点$k$DFS 中的节点对应于深度窗口内的节点。 
2. 维护数组`freq`尺寸为 31（自$a_i \le 10^9$）其中每个条目存储有多少个活动号码设置了该位。 这允许逐位计算异或贡献。 
3.维护一个全局变量`current_score`表示所有有序对的有效值的总和$(u \oplus v)^2$。 我们增量更新它，而不是从头开始重新计算。 
4. 插入值时$v$，使用按位分解计算其对当前活动集的贡献。 对于每个先前有效的值，异或平方可以表示为位总和：

 的$b$第 位贡献$2^{2b}$如果位不同。 使用`freq`，我们确定有多少现有数字有位$b$设置或取消设置并相应地更新分数。 处理贡献后，更新`freq`。 

这样做的原因是插入一个元素只需要考虑它与现有元素的配对，而不是重新计算所有对。 
5. 删除某个值时，反转相同的贡献逻辑：从全局得分中减去其对贡献并递减`freq`。 
6. 在 DFS 期间，在探索节点之前，将其值插入到活动结构中。 插入后，如果其深度窗口有效，则存储`current_score`作为该节点的答案。 
7. 在从DFS返回之前，删除掉出窗口的节点，确保活动集始终准确反映距离内的节点$k$。 

## 为什么它有效

 在每个 DFS 状态下，活动多重集正是与当前节点的深度差最多为 的节点的集合$k$。 分数仅取决于该多重集，并且完全由其中的成对 XOR 交互决定。 

由于异或平方在独立的位位置上进行分解，因此可以使用频率计数增量更新对贡献，而不会丢失信息。 每次插入或删除都会准确更新涉及修改元素的对集，因此不会重复计算或遗漏任何交互。 

DFS 窗口维护保证每个节点在其有效邻域被完全表示一次且仅一次的状态下进行评估。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXB = 31

def add(x, freq, bitcnt):
    # update contribution of x against existing set
    add_score = 0
    for b in range(MAXB):
        xb = (x >> b) & 1
        if xb:
            add_score += (1 << (2 * b)) * (len(freq) - bitcnt[b])
        else:
            add_score += (1 << (2 * b)) * bitcnt[b]

    # update bit counts
    for b in range(MAXB):
        if (x >> b) & 1:
            bitcnt[b] += 1

    freq.append(x)
    return add_score

def remove(x, freq, bitcnt):
    rem_score = 0
    for b in range(MAXB):
        xb = (x >> b) & 1
        if xb:
            rem_score += (1 << (2 * b)) * (len(freq) - bitcnt[b])
        else:
            rem_score += (1 << (2 * b)) * bitcnt[b]

    freq.pop()
    for b in range(MAXB):
        if (x >> b) & 1:
            bitcnt[b] -= 1

    return rem_score

def solve():
    n, k = map(int, input().split())
    a = [0] + list(map(int, input().split()))
    g = [[] for _ in range(n + 1)]
    parent = list(map(int, input().split()))

    for i, p in enumerate(parent, start=2):
        g[p].append(i)

    depth = [0] * (n + 1)
    ans = [0] * (n + 1)

    freq = []
    bitcnt = [0] * MAXB
    current_score = 0

    stack = []

    def dfs(u):
        nonlocal current_score
        stack.append((u, depth[u]))

        # remove nodes too far in depth
        while stack and depth[u] - stack[0][1] > k:
            v, _ = stack.pop(0)
            current_score -= remove(a[v], freq, bitcnt)

        # add current
        current_score += add(a[u], freq, bitcnt)

        ans[u] = current_score

        for v in g[u]:
            depth[v] = depth[u] + 1
            dfs(v)

        # rollback
        current_score -= remove(a[u], freq, bitcnt)
        stack.pop()

    dfs(1)

    print("\n".join(str(x % (1 << 64)) for x in ans[1:]))

if __name__ == "__main__":
    solve()
```该实现保留了活动节点的 DFS 堆栈，并维护了比特位置的频率结构。 插入和删除逻辑确保仅更新涉及当前元素的交互，从而防止重新计算完整的对矩阵。 

一个微妙的点是，该解决方案假设有序对计数，因此每次插入都通过考虑与所有现有元素的交互来隐式地考虑两个方向。 

## 工作示例

 考虑一棵小树，其中节点 1 有子节点 2 和 3，值为`[1, 2, 3]`， 和$k = 1$。 

我们在 DFS 期间跟踪活动集。 

| 步骤| 节点| 活动集| 频率位| 当前分数 |
 | ---| ---| ---| ---| ---|
 | 1 | 1 | {1} | 基于 1 | 0 |
 | 2 | 2 | {1,2} | 更新 | 分数来自 (1,2) |
 | 3 | 返回 1 | {1} | 重置| 0 |
 | 4 | 3 | {1,3} | 更新 | 分数来自 (1,3) |

 这证实了每个节点只能看到其深度 1 的邻域。 

现在考虑一个链 1-2-3-4$k = 2$。 对于节点3，活动集包括{1,2,3}。 该算法维持滑动深度窗口。 

| 步骤| 节点| 活动集| 深度窗口| 当前分数 |
 | ---| ---| ---| ---| ---|
 | 1 | 1 | {1} | [0]| 0 |
 | 2 | 2 | {1,2} | [0,1]| 对(1,2) |
 | 3 | 3 | {1,2,3} | [1,2] 移动 | 全部配对|
 | 4 | 4 | {2,3,4} | [2,3]| 更新 |

 这显示了当深度差超过时如何删除过时的节点$k$。

 ## 边缘情况

 一条链子与$k = n$强制每个节点包含所有祖先。 该算法将所有节点保留在活动集中，并且不会根据深度进行删除。 每个节点的分数累积增长，反映了完整的前缀积累。 

具有根 1 和所有其他子节点的星形树确保除根之外的每个节点都有非常小的邻域。 滑动窗口立即排除不相关的分支，并且每个叶子仅与根交互，验证正确的修剪。 

具有相同值的情况测试当配对匹配时异或贡献是否正确消失。 自从$x \oplus x = 0$，按位贡献逻辑为相同的对产生零增量，因此无论多重性如何，分数都保持稳定。
