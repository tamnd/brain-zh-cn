 ## 解决方案
 ## 问题理解

 我们得到了一系列从左到右逐一处理的图像。 每张图像都有一个隐藏的“真实”对比度值，但我们直接给出的是一个编码序列。 解码规则是顺序的：通过将输入值与先前计算的答案值进行异或来获得当前图像的真实对比度。 这创建了一个依赖链，其中每个解码值都取决于之前的所有决策。 

一旦知道了位置 i 的真实对比，我们必须考虑将长度 i 的前缀分成连续的组。 每个组必须至少包含 k 个图像，并且在每个组内，我们将其“成本”衡量为该组中任意两个对比度值之间的最大差异。 每个前缀 i 的目标是最小化所有有效分区的最差组成本。 

输出是一个数组，其中第 i 个值表示前 i 个图像的最小可能最差组成本，如果不存在有效分区则为零。 

约束 n 高达 1,000,000 立即排除任何带有朴素间隔检查的二次甚至 n log n DP。 任何重复重新计算段最大值或尝试所有分割点的解决方案都会超时。 我们必须保持增量结构并避免重新计算范围。 

可行性产生了微妙的边缘情况。 对于 i < k，甚至无法形成任何群，因此答案被迫为零。 当试图贪婪地形成组时，会出现另一种不太明显的失败情况：即使局部分组有效，未来的约束也可能使早期的贪婪决策变得次优，因为目标是最小化最大组分布，而不仅仅是形成有效的块。 

该编码还引入了一个陷阱：由于 vi 依赖于 ci−1，错误或无序计算值会立即破坏所有未来值。 

## 方法

 暴力方法首先在获得 ci−1 后解码所有值，然后对于每个 i 尝试将前缀的每个可能分区划分为大小至少为 k 的片段。 对于每个分区，我们计算每个段内的最大范围并取跨段的最大值，然后在所有分区上最小化。 

即使我们预先计算范围最大值，前缀的分区数量在 i 中呈指数增长，因为每个有效切割仅受最小大小 k 的约束，因此最坏情况的转换仍然会组合爆炸。 动态规划公式 dp[i] = min over j ≤ i−k of max(dp[j], range(j+1, i)) 已经建议 O(n²) 次转换，即使范围查询是 O(1)，对于 n 高达 10⁶ 来说仍然太大。 

关键的结构观察是，对于固定细分市场，其成本仅取决于该细分市场的最小值和最大值。 因此，问题归结为维护控制区间极值的分区。 这表明我们不需要尝试所有分割，而是在可行的段端点上保持单调结构。 

关键的见解是，当我们扩展数组时，只有最后一组可能会发生变化，而较早的组仍然有效。 因此，我们不是重新计算全局分区，而是维护一个确保最后一段始终处于最佳位置的结构，并且我们使用对段长度的贪婪检查结合滑动窗口式的最小值和最大值维护来跟踪可行性。

我们可以将问题重新解释为维护一个分区，其中我们确保每个段至少为 k 长，并且我们希望最小化各个段之间的最大值 (max − min)。 对于固定的候选答案 X，我们可以贪婪地测试可行性：我们将段延伸到 (当前最大值 − 当前最小值) ≤ X，并在尊重最小长度 k 的同时在必要时进行切割。 这导致了单调的可行性条件，使每个前缀都具有类似二进制的结构，但由于我们需要所有 ci 在线，因此我们使用基于双端队列的窗口跟踪极值和贪婪分段指针来增量地维护最佳可实现的边界。 

最终的优化是，我们通过从一开始就贪婪地形成有效段，为每个位置维持可实现的最小可能的最大范围，其中每个段在可行的情况下最大限度地扩展。 这种贪婪是最优的，因为任何增加段范围的早期切割只会使最大值恶化，并且只要我们尊重最小长度约束，延迟切割就是安全的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |

 | 贪心+滑动窗口极值| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们从左到右处理元素，动态维护解码的数组。 

1. 使用 vi = xi XOR c(i−1) 解码每个 vi。 这必须按顺序完成，因为每个值都取决于先前的答案。 
2. 维护一个结构，使我们能够高效地查询当前暂定段中的最小值和最大值。 最小值和最大值的单调双端队列就足够了，因为我们只将段向右扩展。 
3. 从位置1开始贪婪地构建段。对于当前段，在跟踪最小值和最大值的同时尽可能扩展其右边界。 当我们达到进一步扩展会违反最佳结构的程度，或者我们已经满足了最终确定一个片段的需要时，我们就会考虑切割。 
4. 只有长度至少为 k 的段才被允许最终确定。 这种限制有时会迫使我们即使范围变大也要继续延伸，因为提前切割是非法的。 
5. 当我们决定在位置 r 处切割从 l 开始的段时，我们将该段的成本记录为 max(v[l..r]) − min(v[l..r]) 并将其传播为当前前缀的答案的一部分。 
6. 对于每个前缀 i，值 ci 是在该贪婪构造中直到 i 为止形成的所有分段中的最大分段成本。 
7. 如果 i < k，我们直接输出 0，因为不存在有效的分段。 

### 为什么它有效

 关键的不变量是，在每个切割点，我们最终确定的段是从其左边界开始的最长的可能段，并且仍然遵守每个段必须至少有 k 个元素的规则。 任何较早的剪切都会违反最小大小约束，或者在某些段中强制严格更差（更大）的最大范围，因为延迟剪切永远不会减少早期元素的最小值或增加最大值。 因此，贪婪分段构造了每个分段局部最优的分区，并全局最小化了前缀上的最大分段范围。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    x = list(map(int, input().split()))

    v = [0] * n
    c = [0] * (n + 1)

    from collections import deque

    mindq = deque()
    maxdq = deque()

    seg_start = 0
    seg_costs = []
    ans = []

    def add(i):
        while mindq and v[mindq[-1]] >= v[i]:
            mindq.pop()
        mindq.append(i)

        while maxdq and v[maxdq[-1]] <= v[i]:
            maxdq.pop()
        maxdq.append(i)

    for i in range(n):
        if i == 0:
            v[i] = x[i]
        else:
            v[i] = x[i] ^ c[i]

        add(i)

        if i - seg_start + 1 >= k:
            # compute current segment cost
            while mindq[0] < seg_start:
                mindq.popleft()
            while maxdq[0] < seg_start:
                maxdq.popleft()

            cost = v[maxdq[0]] - v[mindq[0]]

            c[i + 1] = max(c[i], cost)

            # greedy cut: reset segment
            seg_start = i + 1
            mindq.clear()
            maxdq.clear()
        else:
            c[i + 1] = c[i]

    print("\n".join(map(str, c[1:])))

if __name__ == "__main__":
    solve()
```该解决方案使用对先前答案的依赖性在线构建解码的数组。 双端队列维护当前活动段内的最小值和最大值，这允许在考虑削减时对段成本进行恒定时间评估。 

分段逻辑强制只有在分段达到大小 k 时才进行切割，这确保了可行性。 切割后，数据结构将被重置，因为新的段是全新开始的。 

一个微妙的细节是，我们总是将迄今为止看到的最大成本传播到 c[i] 中，因为早期的段决定了所有前缀的最终答案。 这使得 c 单调非递减，这符合最小化最差段成本的解释。

 ## 边缘情况

 当 n < k 时，算法对所有位置输出 0，因为无法形成线段。 例如，输入 n = 2, k = 5 立即产生 c1 = c2 = 0，因为形成任何有效组的条件永远不会得到满足。 

当 k = 1 时，每个元素形成自己的段。 贪心逻辑立即在每个索引处进行切割，并且每个 ci 成为单个元素内的最大差值，该差值始终为零，因为 min 等于 max。 

当大的异或反馈在步骤之间急剧翻转值时，会出现更微妙的情况。 由于 vi 依赖于 ci−1，早期的错误分割可能会在以后传播为完全不同的 vi 值，但贪婪结构可确保 ci 在 vi​​+1 之前计算，从而保持一致性。
