 ## 问题理解

 我们得到一个以任意位置数字系统书写的数字，基数为$x$，其中数字不限于 0-9，而是通过大写和小写字母扩展至总共 62 个不同的符号。 我们的任务是将这个字符串解释为整数值，然后输出以另一个基数表示的相同整数$y$，使用相同的 62 个符号字母表。 

更具体地说，输入为我们提供了源库、目标库以及源库中数字的字符串编码。 我们必须首先将该字符串解码为其真正的整数值，然后将该整数重新编码为目标基数。 

这些约束还不够大，不足以需要任意精度的算术库，但高达 62 个基数的存在以及可能很长的输入字符串意味着我们不能依赖内置的基数转换函数。 我们必须使用整数算术或手动数字处理来仔细模拟转换。 

主要的微妙之处在于输入数字以基数中的字符串形式提供$x$，因此前导零和字符映射很重要。 粗心的实现通常会失败，因为会将字符视为原始 ASCII 值，而不是将它们映射到预期的数值。 

一些边缘情况值得明确说明。 

如果输入的数字是`"0"`，无论基数如何，正确的输出是`"0"`在任何目标基地。 从不单独处理零的简单转换循环可能会输出空字符串。 

如果输入仅使用字母，例如`"FB"`以 16 为基数，很容易错误映射`'F'`为其 ASCII 值而不是 15。例如，解释`'F' - '0'`给出无意义的值并破坏转换。 

如果数字非常大，例如基数为 62 的长字符串，则通过朴素求幂进行直接整数解析可能会存在溢出或过度计算的风险，而逐位累加仍然是安全的。 

## 方法

 强力解释将尝试使用重复求幂将输入字符串转换为整数：对于每个位置，计算$digit \times x^{power}$并对它们求和。 这在数学上是正确的，但计算能力一再导致不必要的重复工作。 对于一个长度的字符串$n$，每个数字的朴素求幂使得复杂性$O(n^2)$，因为每次幂计算成本高达$O(n)$如果迭代地完成。 

更有效和标准的观察是位置数不需要显式的幂。 相反，我们可以从左到右逐步构建值。 每个新数字都会将当前值移动一个因子$x$，然后添加数字。 这将转换转换为线性扫描。 

一旦我们获得整数值，将其转换为基数$y$是对称的。 我们反复除以$y$，收集余数，这些余数直接对应于新基本表示中的数字。 这是位置系统中整数的标准贪婪分解。 

关键的结构思想是，两个转换方向都简化为相同身份的重复应用：基本表示只是基本乘法加上数字的序列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 反复扩功率| O(n²) | O(1) | O(1) | 太慢了|
 | 线性解析+重复除法| O(n + log n) | O(n + log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将这个过程分为两个阶段：将输入字符串解码为整数值，然后将该整数编码为目标基数。 

### 1. 准备数字映射

 我们定义从字符到值的映射：`'0'-'9'`映射到 0-9，`'A'-'Z'`映射到 10-35，并且`'a'-'z'`映射到36-61。 这允许对每个数字进行恒定时间解释。 

此映射至关重要，因为表示形式不是基于 ASCII 的算术，而是自定义字母表。 

### 2. 将 x 基数解码为整数

 我们初始化一个累加器`value = 0`。 对于每个角色`c`在输入字符串中，我们将其转换为数值`d`，然后更新：$$value = value \cdot x + d$$每一步都会将当前数字在基数中左移一位$x$并插入新数字。 

这是有效的，因为位置符号将数字定义为：$$(((d_1 \cdot x + d_2)\cdot x + d_3)\cdots)$$所以递归准确地重建了预期值。 

### 3. 显式处理零

 如果输入是`"0"`（或者计算值为零），我们立即输出`"0"`。 这可以避免在转换期间产生空输出。 

### 4. 将整数转换为以 y 为基数的表示形式

 我们反复对余数取模$y$提取基数中的最低有效数字$y$。 使用数字映射的逆过程将每个余数映射回一个字符。 

我们以相反的顺序收集数字，因为模提取首先产生最低有效数字。 

循环结束后，我们将收集到的字符反转以获得最终的表示。 

### 为什么它有效

 正确性依赖于两个不变量。 在解码过程中，处理完第一个$i$人物，`value`等于长度前缀表示的整数$i$在基地$x$。 编码过程中，每一步，剩余数`value`正是去除已发出的低位数字后的商，因此每个模运算都会提取基数中正确的下一个数字$y$。 这些属性确保两个阶段重建相同的整数而不会产生歧义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def char_to_val(c):
    if '0' <= c <= '9':
        return ord(c) - ord('0')
    if 'A' <= c <= 'Z':
        return ord(c) - ord('A') + 10
    return ord(c) - ord('a') + 36

def val_to_char(v):
    if v < 10:
        return chr(ord('0') + v)
    if v < 36:
        return chr(ord('A') + v - 10)
    return chr(ord('a') + v - 36)

x, y, z = input().split()
x = int(x)
y = int(y)

value = 0
for c in z.strip():
    value = value * x + char_to_val(c)

if value == 0:
    print("0")
    sys.exit()

res = []
while value > 0:
    res.append(val_to_char(value % y))
    value //= y

print("".join(reversed(res)))
```解码循环是解决方案的核心。 它完全避免求幂并维护始终代表基数中已解析前缀的滚动值$x$。 编码循环反映了长除法：每次迭代都会删除最不重要的基数$y$数字。 

一个常见的错误是忘记从输入字符串中去除换行符，这会破坏数字解析。 另一个是错误地处理零，否则会导致空的`res`列表和不正确的输出。

 ## 边缘情况

 的`"0"`输入情况是最重要的边缘情况。 如果我们运行解码循环，`value`保持为零，并且没有保护，编码循环会产生一个空列表。 显式的零检查确保我们立即返回`"0"`。 

对于像这样的情况`"0"`以 62 为基数：

 解码保留`value = 0`。 我们跳过转换和输出`"0"`直接地。 这保留了所有基础的正确性。 

单字符最大数字输入，例如`"z"`测试数字映射是否正确达到 61。然后转换简化为单个模运算序列，并且算法仍然会产生正确的数字而不需要特殊处理。 

这些案例证实映射层和算术转换层在整个 2-62 范围内表现一致。
