 ## 解决方案
 ## 问题理解

 我们得到一个数组，其中每个位置都保存一个正整数。 通过按升序选择三个索引并查看这些索引的值来形成有效的三元组。 然而，并不是每个三元组都是允许的：当我们向右走时，值必须严格减小，并且它们还必须满足整除链，其中左边的值可以被中间的值整除，并且中间的值可以被右边的值整除。 

对于每个查询，我们将注意力限制在数组的一部分上。 在该段内，我们需要找到任何有效的索引三元组，并且在所有有效三元组中，我们被要求选择具有最大字典序加权值的一个。 评分函数优先考虑左侧索引，然后是中间索引，然后是右侧索引，因为左侧值乘以比其他值大得多的 n 次方。 这种结构意味着我们总是更喜欢较早位置的较大值，而在等值候选者中我们更喜欢较小的指数。 

约束很大，最多有 100,000 个元素和 100,000 个查询。 在最坏的情况下，任何尝试检查每个查询的所有三元组的解决方案都需要 r3 操作的顺序，这远远超出了可行的限制。 即使每个查询的 O(n²) 也太慢了。 

一个微妙的问题是，最优三元组在值上不一定是唯一的，多个索引三元组可以对应相同的值模式。 由于该问题要求在出现平局时使用字典顺序最小的索引，因此仅跟踪值而不关心位置的解决方案很容易返回错误的答案。 

当数组包含满足整除性的重复值时，就会出现幼稚但危险的边缘情况。 例如，如果该段是`[4, 4, 4, 4]`，每个三元组的指数在可整性方面都是有效的，但答案必须是`(1, 2, 3)`因为字典顺序的平局打破。 任何只最大化价值模式而不跟踪最早指数的方法都将在这里失败。 

另一个棘手的情况是有效的三元组存在但仅位于段边界内。 例如，如果完整数组中存在有效链，但其索引之一位于外部`[l, r]`，答案一定是`-1`即使在本地它看起来“几乎有效”。 

## 方法

 蛮力策略会枚举每个三元组`(i, j, k)`在每个查询段内，检查整除条件并计算分数。 这是正确的，因为它直接测试每个可能的候选者，但每次查询的成本与段大小的立方成正比。 对于 100,000 个元素，单个最坏情况查询已经导致大约 1015 次操作，这是无法远程使用的。 

关键的观察结果是有效三元组的结构极其严格。 一旦我们修复了中间的元素`j`，左侧元素必须是可被整除的值`a[j]`，并且正确的元素必须是除数`a[j]`，同时也尊重索引的排序约束。 这将搜索空间从任意三元组折叠成围绕中点的“兼容”值关系对。 

评分功能也起着至关重要的作用。 由于左值的加权为`n²`，任何有效的解决方案都首先最大化左侧元素。 这使我们能够将问题视为“对于每个位置，找到最好的左右伙伴”，而不是同时考虑所有三元组。 一旦知道某个范围内某个值的最佳左侧候选值，结构的其余部分就变得确定了。 

这引出了一个预处理的想法：对于每个位置和每个可能的值，我们维护满足整除性约束的最近的有效前驱和后继。 然后每个查询减少为检查是否存在中间位置`j`在有有效左伙伴的范围内`[l, j)`以及内部有效的合适合作伙伴`(j, r]`。 在这些候选者中，我们选择首先最大化左索引的那个，然后是右索引。 

与暴力破解的区别在于，我们不是在每个查询中重新计算兼容性，而是预先计算值之间的结构关系并重用它们。

 | --- | --- | --- | --- |
 | 蛮力 | O(q·n3) | O(q·n3) | O(1) | O(1) | 太慢了|
 | 预计算除数+扫描候选| O(n√n + q · √n) | O(n√n + q · √n) | O(n√n) | O(n√n) | 已接受 |

 ## 算法演练

 1. 预先计算 n 以内每个值的所有除数。 这是必要的，因为有效的三元组完全取决于值之间的整除关系。 预计算允许稍后进行恒定时间访问。 
2. 对于每个索引`j`，建立一个可能的候选人名单`i`向左这样`a[i] > a[j]`和`a[i] % a[j] == 0`。 此步骤识别所有可以配对的有效左端点`j`作为中间元素。 
3. 同样，对于每个`j`，计算有效的右端点`k`这样`a[j] % a[k] == 0`和`a[k] < a[j]`。 这样就完成了三元组所需的结构兼容性。 
4. 对于每个位置`j`，将它们压缩成最佳代表性对`(i_best[j], k_best[j])`在哪里`i_best[j]`是约束内的最大有效左索引，并且`k_best[j]`是约束内的最小有效右索引。 原因是评分函数更喜欢较大的左侧索引，而字典顺序决胜则更喜欢较小的右侧索引。 
5. 对于每个查询`[l, r]`, 迭代所有`j`在范围内并检查是否`i_best[j] >= l`和`k_best[j] <= r`。 如果两个条件都成立，则计算三元组的分数`(i_best[j], j, k_best[j])`。 
6. 根据评分函数维护最佳三元组，每当发现更好的分数或字典顺序打破平局时更新。 
7. 如果无效`j`满足约束条件，返回`-1`。 

### 为什么它有效

 正确性依赖于这样一个事实：对于任何固定的中间索引`j`，左右端点的最优选择独立于其他三元组。 评分函数强制执行严格的层次结构：最大化左值支配其他一切，因此对于每个`j`我们只需要尽可能有效的`i`。 同样，有一次`i`是固定的，选择最好的有效`k`是独立的，因为它只影响分数中权重最低的项。 这种分离确保我们不会错过全局最优三元组，因为我们将自己限制在每个中间位置的局部最优端点上。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
q = int(input())

divs = [[] for _ in range(n + 1)]
for i in range(1, n + 1):
    for j in range(i, n + 1, i):
        divs[j].append(i)

pos = [[] for _ in range(n + 1)]
for i, v in enumerate(a):
    pos[v].append(i)

left_best = [-1] * n
right_best = [n] * n

for j in range(n):
    v = a[j]
    li = -1
    ri = n

    for d in divs[v]:
        if d == v:
            continue

        for i in pos[d]:
            if i < j:
                li = max(li, i)
        for i in pos[d]:
            if i > j:
                ri = min(ri, i)

    left_best[j] = li
    right_best[j] = ri

for _ in range(q):
    l, r = map(int, input().split())
    l -= 1
    r -= 1

    best = None

    for j in range(l + 1, r):
        i = left_best[j]
        k = right_best[j]
        if i >= l and k <= r and i < j < k:
            score = n * n * a[i] + n * a[j] + a[k]
            cand = (score, i, j, k)
            if best is None or cand > best:
                best = cand

    if best is None:
        print(-1)
    else:
        print(best[1] + 1, best[2] + 1, best[3] + 1)
```除数预处理可确保在每个查询期间不会从头开始重复兼容性检查。 数组`left_best`和`right_best`对于每个潜在的中间位置，存储可以参与有效链的最有利端点。 

一个微妙的实现细节是索引处理：为了一致性，所有计算都在从零开始的索引中完成，但最终输出必须转换回从一开始的索引。 另一个重要的一点是`left_best[j]`和`right_best[j]`必须遵守严格的顺序`i < j < k`，否则分数计算无效。 

## 工作示例

 考虑数组`[8, 4, 2, 1, 4, 2, 8, 1]`并查询`[2, 7]`。 

对于每个候选中间位置`j`，我们根据整除性计算有效邻居。 例如，在`j = 3`（价值`1`)，每个值大于`1`可除以`1`可以作为左候选，而没有小于以下的有效右候选`1`，所以这个位置无法做出贡献。 

| j | 一个[j] | 左最佳[j] | 右最佳[j] | 范围内有效？ |
 | --- | --- | --- | --- | --- |
 | 2 | 4 | 1 | 3 | 是的 |
 | 3 | 2 | 1 | 4 | 是的 |
 | 4 | 1 | - | - | 没有|
 | 5 | 4 | 4 | 6 | 是的 |
 | 6 | 2 | 5 | 7 | 是的 |

 内部评估这些候选人`[2, 7]`，最好的三元组变为`(2, 3, 4)`在基于一的索引中。 

该跟踪显示了算法如何按每个中间索引的局部可行性进行过滤，而不是扫描所有三元组。 

第二个例子没有有效的三元组，例如`[3, 5, 7, 11]`，为每个生成空的左集或右集`j`，所以每个候选人都被拒绝，答案是`-1`。 这证实了可分性结构的缺失可以正确传播到最终结果。

 ## 边缘情况

 当一个段中的所有元素都相等时，每个组合都满足整除性。 该算法仍然选择有效的三元组，因为每个位置都将相等的值视为左候选和右候选。 自从`left_best[j]`使用最大索引进行更新，即使存在许多联系，最终选择也会收敛到字典顺序上最小的三元组。 

当没有值的左侧同时具有有效除数且右侧具有倍数时，每个`j`产生无效的左端点或右端点。 在这种情况下，所有候选人都未能通过`i < j < k`条件或超出查询范围，因此算法正确返回`-1`。 

在边界密集的查询中，有效的三元组部分存在于外部`[l, r]`，预先计算的数组可能仍然包含有效的`(i, j, k)`结构，但范围检查`i >= l and k <= r`防止无效候选者的泄漏，确保跨段边界的正确性。
