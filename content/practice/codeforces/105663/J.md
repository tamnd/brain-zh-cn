 ## 解决方案
 ## 问题理解

 游戏发生在$n \times n$开始为空的网格。 两名玩家轮流轮流，第一个玩家总是放置红色令牌，第二个玩家总是放置蓝色令牌。 一次移动并不直接选择一个单元格； 相反，玩家选择一列，令牌就会掉落到该列中最低的未占用单元格，就像基于重力的堆叠系统一样。 一列从下到上逐渐填满，一旦填满就无法再选择。 

每次移动后，我们想知道任一玩家是否已经形成了一条长度的直线$k$只使用他们自己的代币。 该线可以是水平的、垂直的或任一方向的对角线。 如果玩家达到这样的路线，则游戏被认为在该步棋中决定了胜负，我们必须报告谁获胜以及在哪个步数索引。 

输入给出尺寸$n$, 已经进行的步数$m$，和目标长度$k$，后跟所选列的顺序。 根据这个序列，整个棋盘状态必须按照其随时间的演变而准确地重建。 

约束条件允许$n$最多 300 最多$n^2$移动，这意味着网格几乎可以填满。 每次移动后从头开始重新计算获胜条件的解决方案大致可以做到$m \cdot n^2$或者更糟糕的工作，速度太慢。 即使在每次移动后扫描所有可能的线也是不可行的。 

一个更微妙的问题出现在部分评估策略中。 如果仅使用所有方向的简单扫描来检查通过最后放置的令牌的行，那么当令牌堆叠在列中时，粗心的实现可能会重复计数或错过边界对齐的序列。 另一个陷阱是忘记垂直对齐受到重力的限制，因此列中的所有标记形成一个连续的块； 将它们视为任意放置会导致不正确的索引或冗余检查。 

## 方法

 直接的暴力解决方案模拟每次移动，然后检查每个可能的起始单元的长度-$k$在所有四个方向上分段。 对于每一步，都需要扫描$O(n^2)$细胞并在最多四个方向上延伸最多$k$步骤。 最坏情况的复杂度变为$O(m \cdot n^2 \cdot k)$，在全板设置中退化为大约$O(n^5)$。 这远远超出了及时运行的范围。 

关键的观察结果是，获胜条件仅取决于沿四个方向之一对齐的连续段。 我们可以维护从已知结果扩展的动态编程式计数，而不是重复重新计算全局结构。 每个单元可以存储在每个方向上该位置处有多少个相同颜色的连续标记。 当放置新令牌时，仅需要更新它所占据的单元，并且可以在每个方向上以恒定时间从其邻居导出其值。 

这将问题从全局重新计算转变为局部扩展。 网格的行为就像一个不断生长的结构，其中每次移动仅“激活”一个单元格，并且所有相关的线信息都可以从该点向外传播。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每次移动完全重新计算|$O(n^5)$|$O(n^2)$| 太慢了|
 | 每单元定向 DP 更新 |$O(m)$|$O(n^2)$| 已接受 |

 ## 算法演练

 我们维护一个网格，为每个单元格存储四个计数器：以水平、垂直、主对角线和反对角线方向结束于该单元格的连续相同颜色标记的长度。 

1.初始化一个空的$n \times n$grid 和一个跟踪每列当前填充高度的数组。 高度结构至关重要，因为每次移动都会插入到列中最低的可用行中。 
2. 对于每一个动作$i$, 根据 的奇偶性判断轮到谁了$i$。 玩家 1 放置红色标记，玩家 2 放置蓝色标记。 
3. 将标记插入到下一个可用行的所选列中，具体取决于该列的当前高度。 这可以准确地模拟重力，而无需扫描色谱柱。 
4. 对于新占据的单元，计算其方向计数。 对于每个方向，查看该方向上的直接邻居。 如果颜色相同，则将该邻居的计数加一； 否则重置为 1。 这是有效的，因为任何在此单元格结束的有效连续线都必须从前一个相邻的匹配单元格延伸。 
5. 计算完新单元格的所有四个方向值后，检查其中是否有任何一个达到$k$。 如果是这样，当前玩家已经形成了一条在此步结束的有效线，我们可以立即报告获胜者。 
6. 继续，直到处理完所有动作或找到获胜者。 

### 为什么它有效

 从延伸的角度来看，四个方向中任何一个方向上的每个连续线段都有一个唯一的端点。 通过仅存储“结束于单元格”的长度，每个段在其最后一个单元格处精确计数一次。 由于每个新标记仅影响在其位置终止的序列，因此早期状态不需要修改。 这保证了任何长度-$k$必须在放置最后一个标记时检测到线路。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    cols = list(map(int, input().split()))

    # 0 = empty, 1 = red, 2 = blue
    grid = [[0] * n for _ in range(n)]
    height = [0] * n

    # dp arrays: horizontal, vertical, diag1, diag2
    h = [[0] * n for _ in range(n)]
    v = [[0] * n for _ in range(n)]
    d1 = [[0] * n for _ in range(n)]
    d2 = [[0] * n for _ in range(n)]

    for i in range(m):
        c = cols[i] - 1
        r = height[c]
        height[c] += 1

        player = 1 if i % 2 == 0 else 2
        grid[r][c] = player

        # horizontal
        if c > 0 and grid[r][c - 1] == player:
            h[r][c] = h[r][c - 1] + 1
        else:
            h[r][c] = 1

        # vertical
        if r > 0 and grid[r - 1][c] == player:
            v[r][c] = v[r - 1][c] + 1
        else:
            v[r][c] = 1

        # diagonal (\)
        if r > 0 and c > 0 and grid[r - 1][c - 1] == player:
            d1[r][c] = d1[r - 1][c - 1] + 1
        else:
            d1[r][c] = 1

        # anti-diagonal (/)
        if r > 0 and c + 1 < n and grid[r - 1][c + 1] == player:
            d2[r][c] = d2[r - 1][c + 1] + 1
        else:
            d2[r][c] = 1

        if max(h[r][c], v[r][c], d1[r][c], d2[r][c]) >= k:
            print("Ayumi" if player == 1 else "Bunji", i + 1)
            return

    print("No winner")

if __name__ == "__main__":
    solve()
```网格被明确维护，以便重力放置通过以下方式保持恒定时间：`height`大批。 每个定向 DP 表仅在新填充的单元格处更新，使用已计算的邻居值，这避免了任何扫描。 

计算完所有四个方向后立即执行获胜检查。 顺序很重要：如果当前移动形成获胜线，则必须在任何后续移动之前报告。

 ## 边缘情况

 当列已满时，就会出现极端情况。 这`height`数组通过确保我们永远不会尝试插入超出行来防止在该列中进行任何进一步的放置$n-1$。 每次向下扫描的幼稚实现可能会导致覆盖先前的令牌或进入越界索引的风险。 

另一个微妙的情况涉及边界处的对角线传播。 对于放置在顶行或最左/最右列的令牌，必须保护邻居检查。 DP 递归通过在访问相邻单元之前检查边界来自然地处理此问题，确保隔离令牌正确启动长度为 1 的新序列，而不会出现无效的内存访问或不正确的扩展。 

最后一种情况是同一举动中出现多个获胜条件。 由于我们在更新当前单元格后立即进行评估，因此无论其他潜在行如何，在该移动中检测到的第一个获胜都是正确的，因为规则要求报告出现任何获胜的最早移动。
