 ## 解决方案

 ## 问题理解

 我们在数轴上得到一组点，每个点都是三种类型之一的城市：Byteland、Berland 或有争议的城市。 我们可以用电缆连接任意一对城市，而电缆的成本就是两个坐标之间的距离。 

该要求不是单一的全局连接条件。 相反，有两个必须同时成立的独立连接约束。 如果我们忽略所有 Berland 城市，那么每个剩余的城市（Byteland 加上有争议的）仍然必须通过所选电缆连接。 对称地，如果我们忽略所有 Byteland 城市，那么每个剩余的城市（Berland 加上有争议的城市）也必须保持连接。 

目标是在城市之间选择一组无向边，以便连接两个导出子图，同时最小化所有选定边的总长度。 

关键的结构性约束来自这样一个事实：所有城市都位于一条具有固定秩序的线上。 这消除了几何中的任何组合自由：每个有用的连接都可以用排序和邻接来理解，而不是任意配对。 

约束 n 高达 2⋅10^5 强制线性或近线性解。 任何试图考虑所有城市对或对边子集进行全局优化的方法都会立即失败，因为 O(n²) 运算太大了。 

当一种主要类型完全缺失时，就会出现微妙的边缘情况。 如果没有Byteland城市，那么第一个连接要求就变得微不足道，只有Berland加上有争议的问题。 如果没有贝尔兰城市，情况也是如此。 另一种边缘情况是当所有城市都存在争议时，在这种情况下，相邻点上的任何生成树就足够了，问题会分解为一条简单的路径。 

真正的困难在于，这两个连接要求在有争议的城市上重叠，这意味着一些边缘可以同时帮助满足这两个约束。 

## 方法

 一种直接的方法是考虑构建图并搜索满足两个不同连接约束的最小跨越结构。 人们可能会尝试在完整的图上运行最短生成树算法，但该图有 O(n²) 条边，这使得它不可行。 

更接地气的观察来自于线条的几何形状。 在边成本等于距离的线上点上的任何连通图中，最佳结构永远不会使用不必要地跳过中间顶点的交叉捷径。 原因是，用沿线的连续边替换长边 (u, v) 不会增加成本，并且可以保留或改进连接结构。 

这表明唯一有意义的边位于按排序顺序的连续点之间。 一旦我们将注意力限制在相邻对上，问题就变成了选择将哪些相邻边包含在最终结构中。 

现在考虑每个连接需求的真正需求。 对于 Byteland 加上有争议的城市，如果我们按顺序查看仅 B 点和 P 点的序列，则每对连续的此类点必须以某种方式连接，这迫使它们之间的所有中间相邻段都被边缘覆盖。 同样的逻辑也适用于 Berland 加上有争议的城市，我们只考虑 R 和 P 点。 

这会将每个需求转换为对该行的过滤版本的需求。 每个条件独立地迫使我们在其各自的过滤序列中获取所有邻接边。 这两个结构之间唯一的重叠发生在 P 到 P 邻接上，这些邻接出现在两个过滤序列中。

因此，解决方案变成仔细计算两个约束中每个相邻段需要多少次，然后合并共享贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对所有边缘子集进行暴力破解 | 指数| O(n²) | 太慢了|
 | 构建完整图+MST | O(n² log n) | O(n² log n) | O(n²) | 太慢了|
 | 过滤邻接分解| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们按照已经给出的坐标递增顺序处理城市。 

1. 构建相邻距离的基线列表。 对于每对连续的城市 i 和 i+1，计算它们之间的距离。 这些代表了简化为线结构后所有可能的有用边缘。 
2. 计算将所有 Byteland 和争议城市连接在一起所需的成本。 这是通过假装贝尔兰城市不存在来实现的。 在剩下的序列中，每次我们按原始顺序看到两个连续的非 Berland 城市时，我们必须通过它们之间的完整链将它们连接起来，这转化为所有不包含 Berland 断点的相邻对的距离总和。 
3. 通过忽略 Byteland 城市并对位于连续非 Byteland 点之间的所有相邻距离求和，计算 Berland 加上争议城市的对称成本。 
4. 忽略 Byteland 和 Berland，计算仅连接有争议城市的第三个成本。 这捕获了两个早期构造之间共享的邻接贡献。 
5. 使用包含排除逻辑合并结果：Byteland+争议成本和 Berland+争议成本都包含争议城市内部连接的全部成本，因此该部分被计算两次，必须减去一次。 

### 为什么它有效

 当限制为 B+P 节点时，每个有效的解决方案都必须产生一个连通结构。 在一条线上，这会强制连续 B 或 P 点之间的每个间隙由跨越该间隙的边桥接，这相当于为这些间隔内的所有相邻线段付费。 同样的推理也适用于 R+P。 

有争议的城市充当共享连接器，因此两个过滤的视图中都需要两个有争议的城市之间的任何相邻关系。 最后的减法纠正了这种重复计算。 由于每个所需的邻接在组合后都被计算一次，并且不会引入不必要的长边，因此所产生的成本是最小的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    x = []
    c = []
    
    for _ in range(n):
        xi, ci = input().split()
        x.append(int(xi))
        c.append(ci)
    
    if n == 1:
        print(0)
        return
    
    def calc(ignore_type):
        total = 0
        prev_idx = -1
        
        for i in range(n):
            if c[i] == ignore_type:
                continue
            if prev_idx != -1:
                total += abs(x[i] - x[prev_idx])
            prev_idx = i
        
        return total
    
    cost_BP = calc('R')
    cost_RP = calc('B')
    cost_PP = calc('X')
    
    print(cost_BP + cost_RP - cost_PP)

if __name__ == "__main__":
    solve()
```功能`calc(ignore_type)`通过按排序顺序对连续剩余城市之间的距离求和，计算连接除给定类型城市之外的所有城市的总成本。 由于输入已经按坐标排序，因此可以直接捕获该导出子集所需的链连接。 

我们计算三个量：Byteland 加上有争议城市的连接成本、Berland 加上有争议城市的连接成本以及仅有争议的连锁店的连接成本。 最终表达式删除了仅争议连接的重复贡献。 

一个常见的陷阱是尝试仅连接全局最近的邻居而不考虑类型过滤，这忽略了删除一种类型会改变重要邻接的事实。

 ## 边缘情况

 一个关键的边缘情况是其中一种颜色完全消失。 例如，如果没有 Berland 城市，则 Byteland 加上有争议的计算量已经等于所有剩余点的完整链。 减法仍然可以正确执行，因为仅有争议的成本与添加两次的组件之一完全匹配。 

另一个边缘情况是所有城市都存在争议。 在这种情况下，两个过滤计算变得相同，并且减法恰好删除了一个完整副本，在所有点上留下单个跨越链，这是最佳的。 

最后，当类型频繁交替时，每个相邻段都会在至少一次过滤扫描中进行计数，并且重叠减法可确保不会过度计数任何段，即使在最大交错配置中也能保持正确性。
