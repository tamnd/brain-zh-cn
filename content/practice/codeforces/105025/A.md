 ## 问题理解

 我们给定一个整数`a`，可以是负数、零或正数。 我们可以添加一个非负整数`x`到它。 目标是使结果数字`a + x`看起来像数字时钟上显示的有效时间。 

解释是，结果数字被读取为数字序列，该数字序列可以拆分为以下形式的有效 24 小时时间`HH:MM`。 因此，当以前导零书写时，该数字必须恰好有四位数字，并且这些数字必须构成有效时间：从`00`到`23`分钟从`00`到`59`。 

我们并没有尝试所有可能`x`，我们需要最小的非负数`x`这样`a + x`可以格式化为有效的时钟时间。 如果没有这样的`x`存在，我们输出`-1`。 

的限制`a`从`-10^9`到`10^9`，所以相加后的结果值`x`仍在典型的 32 位整数范围内。 这很重要，因为我们可以安全地对候选者进行暴力检查，而不必担心 Python 中的溢出问题。 

一个天真的错误是只检查原始值`a`作为数字，不考虑前导零。 例如，`0`对应于`00:00`， 和`500`对应于`05:00`，即使数字“看起来不像时间”（除非进行填充），这也是有效的。 

另一个微妙的边缘情况是负数。 像这样的数字`-128`添加足够大的值后即可生效`x`，但中间值没有时间意义。 我们只关心最终的非负值。 

## 方法

 直接的方法是尝试增加`x`从零开始计算`a + x`，并检查它在解释为带前导零的四位字符串时是否形成有效时间。 

这是正确的，因为我们明确地搜索最小的`x`，并且增加`x`保证增值`a + x`。 对于每个候选值，验证都是恒定时间：转换为字符串，填充为四位数字，然后检查小时和分钟部分是否有效。 

然而，强力方法可能会在找到有效值之前扫描许多值。 在最坏的情况下，我们可能会检查之间的距离`a`以及下一个有效的 24 小时表示，但由于搜索空间最多约为`10^9`尽管每次检查都很简单，而且在实践中提前终止很快就会发生，所以在 Python 中这仍然是可以接受的。 

关键的观察结果是，24 小时格式的有效时间范围仅从`0000`到`2359`，并且仅存在 1440 个值。 因此，我们不是用任意整数来思考，而是有效地寻找最接近的数字 ≥`a`其最后四位数字构成有效时间。 这将问题减少到在与下一个候选对齐后仅检查一个小的固定范围。 

我们可以进一步简化：我们最多只需要检查从以下位置开始的接下来的 1440 个连续值：`a`，因为在一整天的周期内，每种可能的时间模式都会出现一次。 因此，扫描该有界窗口就足够了。

 ## 算法演练

 1.从给定的数字开始`a`并考虑候选人`a + x`为了增加价值`x`。 目标是找到第一个有效的。 
2. 对于每个候选值`v = a + x`，使用零填充将其转换为 4 位表示形式。 这可以确保像这样的数字`5`变得`0005`，这对于正确的时间解释是必要的。 
3. 将 4 位数字字符串拆分为两部分：前两位数字为小时，后两位数字为分钟。 这符合结构`HHMM`。 
4. 检查小时值是否介于`00`和`23`，分钟值介于`00`和`59`。 如果两个条件都成立，则候选时钟时间是有效的。 
5. 一旦找到有效的候选者，输出`x`因为我们是按升序扫描的，所以这是可能的最小值。 
6. 如果检查完 1440 个值的完整周期后没有找到有效候选者，则输出`-1`因为没有 24 小时时间模式可以从`a`。 

### 为什么它有效

 每个有效时间恰好对应于范围内的一个值`0000`到`2359`。 当我们增加 1 时，我们最终会遍历与时间相对应的所有可能的数字模式。 由于有效时间的空间是有限的，并且完全包含在 1440 个值的周期内，因此任何足够大的偏移最终都必须落在有效配置上（如果可以达到）。 按递增顺序扫描可保证最少性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_valid(v: int) -> bool:
    if v < 0 or v > 2359:
        return False
    h = v // 100
    m = v % 100
    return 0 <= h <= 23 and 0 <= m <= 59

def solve():
    a = int(input().strip())

    for x in range(0, 1441):
        v = a + x
        if is_valid(v):
            print(x)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```该解决方案迭代可能的增量`x`从零开始。 对于每个候选值，它计算`v = a + x`并通过直接分解为小时和分钟来检查有效性。 

条件`v <= 2359`是一个快速修剪步骤：任何大于此的数字都不能代表 HHMM 格式的有效时间，因此它会被立即丢弃。 小时和分钟检查确保正确性。 

循环限制`1441`安全地覆盖整个 24 小时周期内所有可能的过渡，再加上一个额外的步骤来保证边缘对齐情况下的检测。

 ## 边缘情况

 一种重要的边缘情况是初始数字为负数。 例如`a = -1`。 该算法检查：`x = 0 -> v = -1`无效的`x = 1 -> v = 0`有效的 （`00:00`）

 所以它正确返回`1`。 

另一种情况是当`a`已经是一个有效的时间了`0`或者`1100`。 由于循环从`x = 0`，它立即检测有效性并返回`0`。 

第三种情况是无效的分钟编码，例如`a = 59`。 价值`59`对应于`00:59`，这是有效的，因此算法正确返回`0`而不尝试进一步增加。 这强调了验证取决于分割结构，而不是原始数字模式。
