 ## 解决方案
 ## 问题理解

 我们得到了排列成一行的一系列香蕉价格。 每个位置都有一个值，我们可以准确地执行$k$操作，其中一个操作交换两个相邻元素。 

执行这些交换后，我们查看最终的数组并评估每对相邻位置。 对于每个相邻对，我们计算它们值的绝对差，并且我们关心这种差的最大值。 目标是准确地排列数组$k$相邻交换，使得最大相邻差值变得尽可能大。 

关键的困难在于互换是本地的。 尽管我们可以自由地重新排列数组，但移动值的成本取决于它们开始的距离，因为每次交换仅将元素移动一个位置。 

这些限制因素推动$O(n)$或者$O(n \log n)$解决方案。 数组长度可以达到$10^5$， 尽管$k$可以大到$10^{18}$，这立即意味着模拟交换是不可能的。 任何明确处理每个交换的方法都会失败。 

出现微妙的边缘情况时$k = 0$。 在这种情况下，数组根本无法更改，答案只是初始相邻对的最大绝对差。 另一个边缘情况是当$k$非常大。 在这种情况下，数组几乎完全可以重新排列，我们需要了解即使进行多次交换，仍然存在哪些结构限制。 

## 方法

 我们从最直接的解读开始。 我们可以模拟所有序列$k$相邻交换并计算所得的最佳配置。 原则上这是正确的，因为每个状态都可以精确到达$k$掉期对应于有效的安排。 问题在于分支因素。 每个配置都有$O(n)$可能的交换，之后$k$步数呈指数级增长。 即使对于小$n$，这是完全不可行的。 

下一步是停止考虑交换序列，而是考虑元素可以移动多远。 每次交换都会将两个元素的位置改变一步。 如果我们跟踪两个想要相邻的元素，唯一相关的问题是需要多少次交换才能使它们彼此相邻。 

假设我们在位置处取两个值$i$和$j$， 和$i < j$。 为了使它们相邻，我们需要消除它们之间的间隙。 每一次交换最多可以将这个差距缩小一个。 因此，使它们相邻所需的最少交换次数为$j - i - 1$。 这一观察将问题转化为选择一对距离足够小的索引。 

我们可以自由选择任何一对值作为最终的相邻对。 所以我们想要最大化$|c_i - c_j|$受$j - i - 1 \le k$，或等价地$j - i \le k + 1$。 

这次重新制定完全改变了结构。 我们不需要推理排列，只需要考虑位于有界索引距离内的对。 对于每个有效的对，我们想象花费交换将它们组合在一起，并且数组的其余部分始终可以围绕它们进行调整而不影响可行性。 

这导致了滑动窗口视角。 长度段内的任意索引对$k + 2$自动满足距离约束。 相反，任何有效的对都必须位于某个这样的段内。 因此，问题简化为找到任意大小窗口内任意两个值之间的最大差异$k + 2$。 

在固定窗口内，最佳对就是该窗口中的最小值和最大值。 所以我们需要在所有大小的窗口上维护移动窗口的最小值和最大值$k + 2$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力交换模拟 | 指数| O(n) | 太慢了|
 | 距离减小后的最小/最大窗口 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算有效窗口大小$w = k + 2$。 如果$w \ge n$，将整个数组视为一个窗口。 这对应于在允许的交换范围内任意两个元素可以相邻的情况。 
2. 在数组上使用滑动窗口来维护当前窗口中的最大值和最小值。 这是通过两个单调双端队列有效完成的，一个维持最大值的递减值，另一个维持最小值的递增值。 
3. 对于窗口的每个右端点，将新元素插入到两个双端队列中，同时保留单调顺序。 违反单调性的元素被从后面删除。 
4.一旦窗口大小超过$w$，从每个双端队列的前面删除掉出左边界的元素。 
5. 每次窗口调整后，计算最大双端队列的前端和最小双端队列的前端之间的差。 跟踪所有窗口中的最大此类差异。 

这样做的原因是任何最佳解决方案都对应于选择最多之后变得相邻的两个元素$k$互换。 这两个元素最初必须位于距离以内$k+1$，这保证它们一起出现在某个大小的窗口中$k+2$。 在该窗口内，重新排列后的最大可能相邻差值正是其最小值和最大值之间的差值，因为我们始终可以使用窗口约束内允许的交换将这两个值彼此相邻放置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    w = k + 2
    if w >= n:
        print(max(a) - min(a))
        return

    maxdq = deque()
    mindq = deque()
    ans = 0

    l = 0
    for r in range(n):
        while maxdq and a[maxdq[-1]] <= a[r]:
            maxdq.pop()
        maxdq.append(r)

        while mindq and a[mindq[-1]] >= a[r]:
            mindq.pop()
        mindq.append(r)

        if r - l + 1 > w:
            if maxdq[0] == l:
                maxdq.popleft()
            if mindq[0] == l:
                mindq.popleft()
            l += 1

        if r - l + 1 == w:
            ans = max(ans, a[maxdq[0]] - a[mindq[0]])

    print(ans)

if __name__ == "__main__":
    solve()
```该实现将索引而不是值保留在双端队列中，以便我们可以有效地删除滑出窗口的元素。 单调属性确保每个双端队列的前面始终代表当前窗口的极值。 唯一微妙的部分是准确地保持窗口大小，因为窗口大于$k+2$对于归约论证无效。 

## 工作示例

 ### 示例 1

 输入：```
4 0
1 3 2 4
```这里的窗口大小是$k+2 = 2$。 我们只检查相邻对。 

| 窗口| 元素| 最小 | 最大| 差异|
 | ---| ---| ---| ---| ---|
 | [1,3]| 1,3 | 1 | 3 | 2 |
 | [3,2]| 3,2| 2 | 3 | 1 |
 | [2,4]| 2,4| 2 | 4 | 2 |

 最大值为 2，与原始数组中的最佳相邻差异匹配。 

这证实了当不允许交换时，算法简化为扫描相邻对。 

### 示例 2

 输入：```
4 2
1 3 2 4
```现在$w = 4$，所以整个数组是一个窗口。 

| 窗口| 元素| 最小 | 最大| 差异|
 | ---| ---| ---| ---| ---|
 | [1,3,2,4] | 1,3,2,4 | 1 | 4 | 3 |

 结果是 3。这对应于这样一个事实：通过两次交换，我们可以将 1 和 4 放在一起，从而实现最大可能的价差。 

这表明数组变得全局灵活并且只有极值才重要。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个索引进入和离开每个双端队列一次，同时保持滑动窗口 |
 | 空间| O(n) | 双端队列最多存储当前窗口中的所有索引 |

 该解决方案很容易满足限制，因为所有操作都是对数组的线性传递，并且$n \le 10^5$。

 ## 边缘情况

 当$k = 0$，算法集$w = 2$，因此仅考虑相邻对。 这与不允许交换的事实相匹配，因此答案必须直接来自原始配置。 

什么时候$k \ge n - 2$，窗口大小至少变为$n$，所以算法崩溃为计算$\max(c) - \min(c)$。 在这种情况下，任何对都可以相邻，因为有足够的自由度在整个数组中移动元素。 

当所有值相等时，每个窗口产生零差异，并且双端队列正确地保持相同的最大值和最小值。 该算法仍然执行全通，但绝不会高估，因为每个窗口的两端都是相同的。
