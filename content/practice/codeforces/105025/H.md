 ## 解决方案
 ## 问题理解

 我们正在处理一座隐藏的“山”，它定义在一个非常大的网格上$n \times m$。 在这个网格的某个地方有一个特殊的单元格$(x_0, y_0)$，峰值。 其他每个单元格的高度都严格小于该高度，并且高度仅取决于单元格距该峰值的距离。 如果两个单元格距峰值的距离不同，则它们的高度不同，并且越近的单元格总是越高。 

获取信息的唯一方法是查询单元格$(x, y)$，它以实数形式返回其高度。 由此，我们必须使用尽可能少的查询来确定峰的准确坐标。 

限制条件$n, m \le 10^6$立即排除任何检查超过网格一小部分的策略。 即使是一行的完整扫描也已经太大了。 这迫使我们采取一种方法，其中每个查询通常通过利用单调性或单峰性来有意义地减少不确定性。 

一个微妙但重要的属性是高度仅取决于到峰的距离，而不取决于方向。 这意味着如果我们固定一个坐标，比如说$x$，并且变化$y$，该函数的行为就像一条以中心为中心的单峰曲线$y_0$。 如果我们修正同样的情况$y$并有所不同$x$。 这种结构使得问题可以通过对数搜索来解决。 

一个天真的想法是尝试随机点或局部搜索。 然而，由于网格很大，随机采样并不能保证快速达到逐渐更好的点。 在最坏情况的布局中，即使是贪婪的邻居攀爬也会采取太多步骤。 

关键的隐藏边缘情况是峰值靠近边界时。 在这种情况下，局部移动或天真的爬山可能会在到达山顶之前沿着边缘行走很长一段距离，从而浪费查询。 

## 方法

 暴力方法会尝试查询每个单元格，跟踪所看到的最大高度。 这是正确的，因为峰值是唯一的全局最大值。 然而，这需要$n \cdot m$查询，最多可达$10^{12}$，完全不可行。 

关键的观察结果是，虽然该函数存在于二维中，但当另一个坐标固定时，它在每个坐标中都是单峰的。 如果我们修复$x$，然后当我们继续前进时$y$，到峰值的距离减小，直到$y_0$，然后增加。 所以沿着这条线的高度有一个最大值。 这正是三元搜索所需的结构。 

这将 2D 问题简化为两个独立的 1D 搜索。 首先我们找到正确的行$y_0$通过三元搜索$y$，使用任何固定的$x$。 一次$y_0$发现，我们沿着$x$- 轴定位$x_0$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(nm)$|$O(1)$| 太慢了|
 | 两阶段三元搜索 |$O(\log n + \log m)$|$O(1)$| 已接受 |

 ## 算法演练

 我们将交互函数视为每个坐标中的黑盒单峰函数。 

1.修复任何$x$，为了方便取$x = 1$。 我们现在考虑这个函数$f(y) = \text{height}(1, y)$。 由于高度仅取决于到峰的距离，因此该函数在以下位置有一个最大值：$y = y_0$。 
2. 对区间进行三元搜索$[1, m]$定位$y_0$。 每一步选择两个中点$mid_1$和$mid_2$， 询问$(1, mid_1)$和$(1, mid_2)$，并比较高度。 如果函数较高于$mid_1$，峰值位于左段，否则位于右段。 这是有效的，因为单峰性保证没有次要最大值。 
3. 缩小范围后，直接测试剩下的几个候选者，以确定准确的$y_0$。 
4.现在修复$y = y_0$。 考虑$g(x) = \text{height}(x, y_0)$，这又是单峰的，在$x_0$。 
5. 运行三元搜索$[1, n]$同样的方式，查询$(mid, y_0)$直到达到峰值位置$x_0$被发现。 
6. 输出$(x_0, y_0)$并终止。 

### 为什么它有效

 正确性依赖于这样一个事实：到峰值的距离在以下位置被严格最小化：$(x_0, y_0)$，并且当我们向任何方向移动时严格增加。 因此，任何固定的水平或垂直切片形成具有单个最大值的严格单峰函数。 这种函数的三元搜索永远不会丢弃真正的峰值，因为两点之间的比较总是正确地指示哪一侧包含最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(x, y):
    print(f"? {x} {y}")
    sys.stdout.flush()
    return float(input().strip())

def ternary_search_fixed_x(x, m):
    l, r = 1, m
    while r - l > 3:
        m1 = l + (r - l) // 3
        m2 = r - (r - l) // 3
        v1 = ask(x, m1)
        v2 = ask(x, m2)
        if v1 < v2:
            l = m1
        else:
            r = m2

    best_y = l
    best_val = ask(x, l)
    for y in range(l + 1, r + 1):
        v = ask(x, y)
        if v > best_val:
            best_val = v
            best_y = y
    return best_y

def ternary_search_fixed_y(y, n):
    l, r = 1, n
    while r - l > 3:
        m1 = l + (r - l) // 3
        m2 = r - (r - l) // 3
        v1 = ask(m1, y)
        v2 = ask(m2, y)
        if v1 < v2:
            l = m1
        else:
            r = m2

    best_x = l
    best_val = ask(l, y)
    for x in range(l + 1, r + 1):
        v = ask(x, y)
        if v > best_val:
            best_val = v
            best_x = x
    return best_x

def solve():
    n, m = map(int, input().split())
    y0 = ternary_search_fixed_x(1, m)
    x0 = ternary_search_fixed_y(y0, n)
    print(f"! {x0} {y0}")
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该实现将两个坐标搜索完全分开。 辅助函数`ask`确保每次查询后刷新，这在交互式问题中是强制性的。 

每个三元搜索循环根据比较两个内部点来缩小间隔。 一旦间隔很小时，线性扫描就会安全地解析出精确的最大值，从而避免小范围内的浮点比较不稳定。

 ## 边缘情况

 当峰值恰好位于边界上时，就会出现极端情况，例如$(1, 1)$。 在这种情况下，函数沿两个轴仍然是单峰的，但最大值位于搜索区间的边缘。 三元搜索仍然有效，因为比较总是倾向于包含峰值的边界方向，并逐渐向它收缩。 

另一种情况是当$n = 1$或者$m = 1$。 该问题退化为纯粹的一维三元搜索。 适用相同的逻辑，但只需要一个阶段。 该算法仍然表现正确，因为单峰性假设仍然有效。 

最后，当峰居中时，对称点之间的比较会产生几乎相同的还原模式，但高度的严格不平等确保了向中心的确定性移动而不会振荡。
