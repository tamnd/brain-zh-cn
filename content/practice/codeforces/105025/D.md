 ## 解决方案
 ## 问题理解

 我们有两组有序的汽车在固定的时刻沿着笔直的道路排列。 一组远离原点，另一组则以相同的速度向原点移动。 每当两辆车相遇时，也就是说，当它们在路上擦肩而过时，在该相遇瞬间每有两辆车参与，马塞尔的不适感就会增加一分。 

关键细节是多辆车可以同时出现。 如果在某个时间多辆汽车在同一地点相遇，则其中的每一对汽车都会分别做出贡献。 因此，如果 k 辆车同时相遇，贡献就是该组内对的数量，即 k(k−1)/2。 

输入给出 n 辆向右移动的汽车和 m 辆向左移动的汽车的初始位置。 因为所有速度都相等，所以每组内汽车的顺序永远不会改变，并且来自相反方向的每对汽车只会相遇一次。 

输出是来自不同方向的所有汽车对的此类会议的总数。 

每个方向的约束最多为 3×10^5 辆汽车，因此不可能对所有对进行任何二次模拟。 即使是 O(nm) 的直接配对也太大了，因为在最坏的情况下它达到了大约 9×10^10 次操作。 

微妙的边缘情况来自同时发生的碰撞。 如果几辆向右移动的汽车和向左移动的汽车在完全相同的点相遇，计数必须正确处理重数。 

例如，如果职位是：```
n = 2, m = 2
a = [1, 3]
b = [2, 4]
```然后两人在不同的时间见面，因此每个人都独立做出贡献。 但是，如果我们移动值以便在同一时间发生多个交叉点，则仅计算成对顺序而不进行分组的天真的合并逻辑将根据实现的不同而低估或过度计算。 

另一种棘手的情况是当整个组严格位于另一组之前时，例如：```
a = [1, 2, 3]
b = [10, 11]
```这里每一对都交叉，答案就是 n × m。 任何尝试仅匹配最近邻居的解决方案都会失败。 

## 方法

 蛮力的想法很简单：对于第一组中的每辆车，模拟其运动并计算它遇到的第二组中的汽车数量。 由于所有汽车都以恒定速度移动，因此两辆车在其初始顺序意味着它们的路径交叉时恰好相遇。 这简化为检查所有对 (i, j) 并在正确的时间排序时，如果第 i 个向右移动的汽车位于第 j 个向左移动的汽车的左侧，则增加答案。 这是正确的，但成本为 O(nm)，远远超出了限制。 

为了改进，我们观察到运动是均匀的，所以时间并不重要。 重要的是相对顺序。 从位置 a[i] 开始的向右移动的汽车将与从位置 b[j] 开始的每个向左移动的汽车相遇，使得它们的路径在时间上相交，这相当于在一致方向索引下解释时的 a[i] < b[j]。 

然而，问题不仅仅是对排序数组中的所有对进行简单比较，因为直接计数仍然看起来像 O(nm)。 关键的见解是将这种情况解释为沿线的横扫。 每次我们从左到右穿过一个位置时，我们都会根据视点累积有多少来自另一个方向的车辆位于该点之外或之前。 

由于两个数组都已排序，因此我们可以使用双指针扫描来处理它们。 我们沿着增加的位置移动，并保持相反方向有多少辆车会与当前的车相遇。 每辆新车要么贡献所有以前见过的相反方向的汽车，要么决定它将遇到多少未来的汽车。 这将计数减少为线性时间。 

基本结构是每对都是由合并排序序列中的相对顺序确定的，因此我们可以计算两个数组之间的交叉反转。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了|
 | 两点横扫 | O(n + m) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将此视为计算有多少对索引 (i, j) 满足汽车必须恰好经过对方一次。 由于所有速度都相同，因此这成为计算一个排序列表中有多少元素位于最终合并顺序中另一个列表中每个元素的相对侧的问题。 

我们利用排序和扫描：

 1. 我们从数组 a 和 b 的开头处的两个指针 i 和 j 开始。 我们还维护一个计数器，用于跟踪相对于第一组的扫描中已经“看到”了第二组的汽车数量。 
2. 我们比较a[i]和b[j]。 较小的位置代表沿路从左到右顺序排列的下一辆车。 
3. 如果 a[i] < b[j]，则第一组中的汽车当前是空间顺序中的下一个。 这意味着一旦我们处理完第二组中仍然领先的所有剩余车辆，它将满足这些车辆的需求。 我们相应地添加已处理的相反方向汽车的数量，然后将 i 向前移动。 
4. 否则，如果b[j] < a[i]，我们首先处理第二组车。 这辆车将满足所有已处理的第一组车辆，因此我们积累这些贡献并向前推进。 
5. 继续，直到两个阵列都耗尽。 一个阵列完成后，另一组中的剩余元素将与已计入扫描中的所有相反方向的汽车一起贡献。 
6. 最终累计值为两两相遇的总次数。 

这种排序之所以有效的原因是，在处理排序顺序中的后一个元素时，每对都只计算一次。 扫描可确保在已处理段和未处理段之间的正确边界处对每个交叉对进行计数。 

### 为什么它有效

在扫描的任何时刻，我们都会按排序顺序将行划分为“已处理的前缀”和“未处理的后缀”。 每对 (a[i], b[j]) 由处理两个位置中较大的一个的时刻唯一标识。 此时，另一个元素已经完全分类为已处理前缀内或剩余后缀内，因此该对的贡献仅添加一次。 没有对可以提前计数，因为两个端点都没有被处理，并且不能稍后计数，因为两个端点都已经位于扫描边界后面。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    i = j = 0
    cnt_a = 0
    cnt_b = 0
    ans = 0
    
    while i < n or j < m:
        if j == m or (i < n and a[i] < b[j]):
            ans += cnt_b
            cnt_a += 1
            i += 1
        else:
            ans += cnt_a
            cnt_b += 1
            j += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```该实现在两个排序数组上使用经典的两指针合并结构。 变量`cnt_a`和`cnt_b`表示每组中有多少元素已在扫描中得到处理。 当处理一组中的元素时，我们添加另一组中已处理的元素的数量，这恰好对应于该元素与先前处理的元素贡献的有效交集的数量。 

比较`a[i] < b[j]`确保严格排序与问题陈述一致，即所有位置都是不同的，因此不会发生联系。 最终循环条件确保一旦一个数组耗尽，另一组中的所有剩余元素都将在相反计数器的全部贡献下进行处理。

 ## 边缘情况

 一种关键的边缘情况是一个数组的所有元素都小于另一个数组的所有元素。 例如：```
n = 3, m = 2
a = [1, 2, 3]
b = [10, 11]
```在扫描过程中，每个元素`a`首先被处理，所以`cnt_b`在我们开始消费之前始终为零`b`。 当我们到达`b`，每个元素贡献`cnt_a`，增长到 3。因此贡献为 3 + 3 = 6，匹配完整的笛卡尔配对。 

另一种情况是严格交替：```
a = [1, 4, 7]
b = [2, 5, 8]
```在这里，每一步都交织在一起。 每个`a[i]`只能看到之前处理过的`b`，以及每个`b[j]`看到之前处理过的`a`，确保每个交叉对都被精确计数一次。 扫描保证不会跳过任何对，因为每个新元素都会立即考虑相反类型的所有早期元素。
