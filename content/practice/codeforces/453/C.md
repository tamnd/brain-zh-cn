 ## 解决方案
 ## 问题理解

 我们得到一个无向图，对于每个顶点，该顶点在一次行走中必须出现的次数的奇偶性。 

行走由一系列顶点表示。 序列中的连续顶点必须通过边连接。 顶点和边可能会被多次重新访问。 步行可以在任何地方开始和结束，甚至可能是空的。 

对于每个顶点`v`，我们知道它在最后的行走中是否必须出现偶数次或奇数次。 我们的任务是构造任何有效的步行，其访问计数与所有所需的奇偶校验相匹配。 如果不存在这样的步行，我们输出`-1`。 

该图最多包含`10^5`顶点和`10^5`边缘。 任何试图搜索可能的行走的解决方案都是不可能的。 即使存储所有候选状态也会发生组合爆炸。 这些约束强烈表明线性或接近线性的图遍历。 

最重要的观察是只有奇偶校验才重要。 我们不关心一个顶点被访问了 1 次还是 17 次，只关心次数是奇数还是偶数。 涉及奇偶校验的问题通常会变得更加简单，因为添加两次访问会抵消模 2。 

一些边缘情况很容易被错误处理。 

考虑一个断开连接的图：```
4 1
1 2
1 0 1 0
```顶点 3 和 4 与包含顶点 1 的组件隔离。顶点 3 需要奇奇偶校验。 由于步行无法从另一个组件到达它，因此答案是不可能的。 

另一个微妙的情况是当所有奇偶校验为零时：```
3 2
1 2
2 3
0 0 0
```空走是有效的。 始终在某处启动 DFS 的解决方案会不必要地引入访问并破坏奇偶校验要求。 

当所需的奇数顶点总数为奇数时，会出现第三种棘手的情况：```
2 1
1 2
1 0
```这个其实是可以解决的。 步行`[1]`访问顶点 1 一次，访问顶点 2 零次。 

许多图奇偶校验问题需要偶数个奇数顶点，但该规则适用于欧拉路径中的边度。 这里我们统计顶点出现的次数，所以条件是不同的。 

## 方法

 暴力方法会尝试构建一条行走并跟踪所有顶点的奇偶向量。 每个状态由当前顶点和迄今为止访问的每个顶点的奇偶校验组成。 

即使对于只有 30 个顶点的图，也有`2^30`可能的奇偶校验掩码。 和`10^5`顶点，状态空间大得难以想象。 这个方向是没有希望的。 

关键的观察是我们不需要寻找散步。 我们可以直接使用 DFS 树构建一棵。 

假设我们选择某个根并执行 DFS。 当 DFS 处理完子树并返回到父树时，我们就知道该子树是否已经满足所有奇偶校验要求。 

如果某个顶点当前具有错误的奇偶校验，我们可以通过记录对该顶点的一次额外访问来在本地修复它。 这样做只会翻转该顶点的奇偶性。 当我们返回父级时，父级的奇偶校验也会发生变化，因为 DFS 遍历再次访问父级。 

这表明从叶子向上处理顶点。 在控制权返回到其父树之前，每个子树都可以变得正确。 唯一不能自由调整奇偶校验的顶点是 DFS 根，因为它上面没有父节点。 

这将问题转化为连接组件上的建设性 DFS。 我们生成实际的步行，同时修复奇偶校验。 

该图可能已断开。 任何需要奇校验的顶点必须属于所选的 DFS 组件，否则永远无法访问它。 我们通过在所需奇偶校验为 1 的顶点中选择一个根来处理此问题。如果不存在这样的顶点，则空游已经有效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最优DFS构建| O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 读取图形和所需的奇偶校验数组。 
2. 计算有多少个顶点需要奇校验。 
3. 如果该计数为零，则输出空走。 每个顶点已经具有偶校验，因为它被访问了零次。 
4. 选择所需奇偶校验为 1 的任意顶点作为 DFS 根。 
5. 从此根运行 DFS。 
6.当DFS第一次进入一个顶点时`v`, 附加`v`到答案序列并翻转当前的奇偶校验状态`v`。 
7. 对于每一个未被拜访过的邻居`to`，递归地处理那个孩子。 
8.从孩子那里回来后，附加`v`再次翻转奇偶校验状态`v`。 

这对应于沿着 DFS 树边缘往回走。 
9、处理完所有children后，比较当前的奇偶校验`v`具有所需的奇偶性。 
10. 如果它们不同并且`v`不是根，追加`v`再次翻转其奇偶校验。 然后附加其父级并翻转父级的奇偶校验。 

这表示额外遍历树边缘一次。 它修复了`v`永久地同时将奇偶校验差异向上推到父级。 
11. 如果它们不同并且`v`是根源，根源无法将差异推到任何地方。 施工失败。 
12. DFS完成后，检查是否访问了每个需要奇偶校验1的顶点。 如果不是，则某些所需的顶点位于另一个连接的组件中，因此输出`-1`。 
13. 否则输出构造的序列。 

### 为什么它有效

 DFS 保持不变性，即一旦非根顶点的处理完成，该顶点的奇偶校验就完全符合其要求，并且永远不会再改变。 

首先处理叶子。 如果叶子的奇偶校验不正确，则对该叶子的一次额外访问并返回其父节点只会翻转该叶子和父节点。 叶子永远变得正确。 

归纳起来，当处理内部顶点时，所有子子树都已经固定。 当前顶点处任何剩余的不匹配都可以通过完全相同的方式进行纠正，即通过其父边添加一次额外的遍历。 

每个奇偶校验差异都通过 DFS 树向上推送。 最终，所有的差异都会在根源上累积起来。 如果根的奇偶校验也符合其要求，则每个顶点都是正确的。 如果不是，则该连接组件内不存在有效的遍历，因为根之上没有父级来吸收最终的不匹配。 

生成的序列始终是有效的行走，因为每对连续的记录顶点都对应于遍历图的边。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    need = list(map(int, input().split()))

    root = -1
    for i in range(n):
        if need[i]:
            root = i
            break

    if root == -1:
        print(0)
        print()
        return

    visited = [False] * n
    cur = [0] * n
    ans = []

    sys.setrecursionlimit(300000)

    def dfs(v, parent):
        visited[v] = True

        ans.append(v + 1)
        cur[v] ^= 1

        for to in g[v]:
            if to == parent:
                continue
            if visited[to]:
                continue

            dfs(to, v)

            ans.append(v + 1)
            cur[v] ^= 1

        if cur[v] != need[v]:
            if parent == -1:
                return False

            ans.append(parent + 1)
            cur[parent] ^= 1

        return True

    ok = dfs(root, -1)

    if not ok:
        print(-1)
        return

    for i in range(n):
        if need[i] and not visited[i]:
            print(-1)
            return

    print(len(ans))
    print(*ans)

solve()
```数组`cur`存储当前构建的步行达到的奇偶性。 每次将一个顶点附加到答案序列时，其奇偶校验都会翻转。 

输入一个顶点会贡献一次访问，因此我们立即附加它并切换`cur[v]`。 

从子级返回后，步行实际上回到了父级，因此我们再次附加父级。 这与实际遍历相匹配并正确更新奇偶校验。 

最微妙的部分是失配校正。 当非根顶点以错误的奇偶校验结束时，我们追加其父顶点。 当前顶点已经是序列中的最后一个顶点，因此移动到父顶点会对该树边执行一次额外的遍历。 这会翻转父奇偶校验，同时保持子奇偶校验不变。 

根很特殊。 其他每个顶点都可以向上推动奇偶校验不匹配，但根无处可发送它。 如果根仍然不正确，则不存在解决方案。 

最终的连接检查至关重要。 包含所需奇数顶点的断开组件永远无法从所选根到达。 如果没有此检查，算法将错误地输出部分解决方案。

def run(inp: str) -> str:

        v -= 1

    need = list(map(int, input().split()))

    root = next((i for i, x in enumerate(need) if x), -1)

    if root == -1:
        return "0\n\n"

    cur = [0] * n
    ans = []

    sys.setrecursionlimit(1000000)

        ans.append(v + 1)

    for i in range(n):
        if need[i] and not vis[i]:
            return "-1\n"

    return str(len(ans)) + "\n" + " ".join(map(str, ans)) + "\n"

 ## 边缘情况

 考虑一个断开连接的图：```
4 1
1 2
1 0 1 0
```该算法选择顶点 1 作为根，并且仅探索顶点 1 和 2。顶点 3 仍然需要奇奇偶校验，但仍然未被访问。 最终验证检测到这一点并输出`-1`。 

考虑所有奇偶校验都为零：```
3 2
1 2
2 3
0 0 0
```不存在所需奇偶校验为 1 的根。 该算法立即输出空游。 每个顶点出现零次，这是偶数。 

考虑一个孤立的奇数顶点：```
1 0
1
```DFS 从唯一的顶点开始，记录一次，然后结束。 它的奇偶校验已经是正确的。 输出很简单：```
1
1
```这种情况证实了根本身可以满足整个要求，而无需遍历任何边。 

考虑两个不相连的奇数顶点：```
2 0
1 1
```无论选择哪个奇数顶点作为根，都无法到达另一个顶点。 最终的连通性检查失败，算法输出`-1`。 这正确地捕捉到了这样一个事实：没有任何一次步行可以访问两个断开连接的组件的顶点。
