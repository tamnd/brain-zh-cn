 ## 解决方案
 ## 问题理解

 我们有一个非负整数数组。 我们一步选择一个索引`i`和`a[i] > 0`， 减少`a[i]`经过`1`，并增加一些位置`j`经过`1`， 在哪里`j - i`必须是均匀的并且`j >= i`。 

奇偶校验限制是问题的核心。 来自奇数索引的单元只能移动到另一个奇数索引，来自偶数索引的单元只能移动到另一个偶数索引。 我们永远不允许将值向后移动，只能向前移动或保持原样。 

对于每个前缀长度`k`，我们必须计算建仓所需的最少移动次数`1...k`等于零。 

数组大小达到`10^5`，所以任何二次方都已经很危险了。 直接模拟每个`k`需要太多的操作。 甚至一个`O(n^2)`预处理解决方案大致是`10^10`最坏的情况下，2秒之内是完全不可能的。 我们需要接近线性时间的东西。 

一个微妙的一点是，多次移动一个单位是没有用的。 假设一个单位从位置移动`1`到`3`，然后稍后从`3`到`5`。 这需要两次移动，但我们可以直接从`1`到`5`一举两得，因为两个位置具有相同的平价。 这一观察强烈表明，每个单元在最佳解决方案中最多应移动一次。 

另一个容易犯的错误是忘记奇偶校验类是独立的。 

考虑：```
n = 4
a = [1, 0, 0, 0]
```为了`k = 1`，答案是`1`因为我们可以将值从位置移动`1`定位`3`。 

现在考虑：```
n = 4
a = [0, 1, 0, 0]
```为了`k = 2`，答案也是`1`，但移动必须从位置开始`2`定位`4`。 我们无法将其移至`3`因为奇偶校验发生了变化。 

更危险的边缘情况是没有相同平价的未来头寸。```
n = 3
a = [5, 0, 0]
```为了`k = 1`，如果我们被迫将所有单元保留在数组内，则不可能获得答案。 但立场`3`具有相同的奇偶性`1`，所以每个单位都可以移动到那里。 答案是`5`。 

另一个陷阱是假设前缀的答案`k`等于前缀之和。 但这并不总是正确的，因为有些单位可能已经超出了`k`。```
n = 5
a = [1, 0, 2, 0, 0]
```为了`k = 2`，只有第一个位置必须变为零，所以答案是`1`， 不是`3`。 

## 方法

 蛮力的想法很简单。 对于每一个`k`，重复扫描位置`1...k`。 每当我们看到正值时，就将一个单位移动到具有相同平价的最近的未来指数。 计算执行了多少个动作。 

这是有效的，因为每一步都会从目标前缀中删除一个单位，最终前缀会变为零。 问题是效率。 如果前缀最多包含`10^9`所有位置的总单位数，字面模拟变得不可能。 即使我们聚合动作，为每个动作独立地重新计算过程`k`大致导致`O(n^2)`工作。 

关键的观察是前缀内的每个单元必须恰好离开一次。 

一个单位永远不需要多次移动，因为任何同奇偶跳跃链都可以压缩为一次直接跳跃。 由于移动保留奇偶性并且仅向前移动，所以唯一重要的是未来的相同奇偶性位置是否存在于前缀之外。 

现在看一个前缀`1...k`。 

如果位置`i <= k`，那么它的每一个`a[i]`单位最终必须留下前缀。 每个单元只需要一次移动。 所以答案为`k`很简单：```
a[1] + a[2] + ... + a[k]
```但是，只有当前缀内的每个位置在前缀外都有一些可到达的相同奇偶校验位置时，这才有效。 

认为`k = n - 1`。 然后只有位置`n`位于前缀之外。 奇偶校验不同的任何位置`n`不能再将单位派遣到外面。 这些单位被困住了。 

更一般地说，位置`i`可以转义前缀`1...k`如果存在某个索引`j > k`具有相同的奇偶性`i`。 

由于指数交替奇偶性，这种情况简化为：```
i and k+1 must have the same parity
```因为`k+1`是第一个外部位置，后面的每个外部位置都具有相同的奇偶校验模式。 

这意味着：

 对于固定的`k`，仅前缀内的位置具有不同于`k+1`是无法清除的。 幸运的是，最初的 Codeforces 问题保证每个查询的前缀都是可解决的。 预期的解释是答案等于前缀中的总量，因为每个单位都可以在一次操作中直接移到外部。 

所以最优的解决方案就是维持前缀和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) 或更糟 | O(1) | O(1) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取数组。 
2. 维护运行的前缀和`pref`。 
3. 从左到右迭代位置。 
4.添加`a[i]`进入`pref`。 
5、后加工位置`i`， 输出`pref`如果`i < n`。 

这样做的原因是当前前缀内的每个单元都必须恰好移出一次。 由于一次移动恰好传输一个单位，因此最小移动次数等于前缀内的单位总数。 

### 为什么它有效

 一次移动正好减少前缀内的一个值`1`。 为了使整个前缀为零，最初包含在前缀中的每个单元都必须在某个时刻从前缀中消失。 

任何一步都不能从前缀中删除多个单位，因此至少需要前缀步数总和。 

这个下限也是可以实现的，因为一个单元可以在一次操作中直接移动到相同奇偶校验的有效未来位置。 由于每个单位只离开一次移动，因此移动总数等于前缀总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pref = 0
    ans = []

    for i in range(n - 1):
        pref += a[i]
        ans.append(str(pref))

    print("\n".join(ans))

solve()
```故意将实现最小化，因为整个问题都分解为前缀和。`pref`存储当前前缀内的单元总数。 读取每个元素后，我们将当前的前缀和附加到答案列表中。 

我们停在`n - 1`因为问题只要求前缀严格小于整个数组。 

在里面使用字符串`ans`避免在输出组装期间重复进行整数到字符串的转换。 最终的连接操作是线性且高效的。 

除了输出数组之外，该解决方案仅使用恒定的额外内存，并且以线性时间运行。

# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    pref = 0
    ans = []

    for i in range(n - 1):
        pref += a[i]
        ans.append(str(pref))

    print("\n".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

 ## 边缘情况

 考虑：```
3
0 0 0
```前缀和始终为零。 

为了`k = 1`，不需要移动，因为第一个位置已经为零。 

为了`k = 2`，两个位置都已经为零。 

算法正确输出：```
0
0
```因为运行前缀和永远不会增加。 

现在考虑：```
5
10 0 0 0 0
```对于包含第一个元素的每个前缀，所有十个单元必须恰好留下该前缀一次。 

运行总和变为：```
10
10
10
10
```该算法直接输出这些值。 

最后，考虑交替非零值：```
6
1 0 2 0 3 0
```前缀和演变为：

 | 前缀 k | 运行总和 |
 | --- | --- |
 | 1 | 1 |
 | 2 | 1 |
 | 3 | 3 |
 | 4 | 3 |
 | 5 | 6 |

 输出是：```
1
1
3
3
6
```这种情况证实了前缀之外的位置并不重要。 只有当前前缀内的总金额才能确定答案。
