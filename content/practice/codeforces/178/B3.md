 ## 解决方案
 ## 问题理解

 我们得到一个无向连通图，其中城市是节点，道路是边。 对于每个商人，我们还提供了一对城市：仓库城市和商店城市。 商家需要使用图中的任意路径将货物从仓库运送到商店。 

如果一条道路的拆除会破坏商人两个城市之间所有可能的路径，那么该道路对于商人来说就是“重要的”。 在图术语中，这意味着道路位于两个选定顶点之间的每条路径上，即，它是相对于该特定端点对的桥梁，不一定是整个图的全局桥梁。 

对于每个查询对，我们必须计算有多少条边对于两个端点之间的连接是不可避免的。 

图大小最多为 10^5 个节点和边，最多有 10^5 个查询。 这立即排除了任何根据查询重新计算连接性的方法。 在最坏的情况下，即使每个查询的 O(m) 也会导致大约 10^10 次操作，这是不可行的。 该解决方案必须对图进行预处理，以便在亚线性或接近恒定的时间内回答每个查询。 

当图形包含循环时，会出现微妙的边缘情况。 例如，如果图是一个简单的三角形 1-2-3-1 并且查询是 (1,3)，则不需要边，因为有两条不相交的路线。 答案是 0。简单的最短路径或基于 DFS 的单路径推理会错误地将某些边视为必要的。 

另一种边缘情况是当图已经是一棵树时。 然后，每对节点都有一条唯一的路径，因此该路径上的每条边都很重要，答案就是树中的距离。 

## 方法

 一个直接的想法是通过尝试测试每个边来独立处理每个查询：将其删除并检查两个端点是否仍然连接。 对于 m 个边和 k 个查询，如果每次删除都使用 BFS/DFS 天真地完成，这将变为 O(km(m + n))，这是完全不可行的。 

一个稍微好一点但仍然太慢的想法是为每个查询计算来自源的 DFS 并标记找到的路径上的所有桥。 然而，这仍然需要对每个查询重新进行遍历，并且循环使得不可能将注意力限制在单个路径上。 

关键的观察结果是，两个节点之间“始终需要”的边正是位于端点组件之间的唯一路径上的_2边连接组件树_（桥树）中的桥。 一旦我们将每个 2 边连接的组件收缩为单个节点，所有剩余的边就形成一棵树。 在这棵树中，每条边都是全局的一座桥，任意两个节点之间只有一条简单路径。 因此，两个原始节点之间不可避免的边数等于其组件代表之间的桥树边数。 

这将问题简化为构建桥接树并回答树上的路径长度查询，这可以使用 LCA 或深度差异来完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的暴力破解 | O(k·m·(n+m)) | O(n+m) | 太慢了|
 | 桥分解+LCA | O(n + m + k log n) | O(n + m + k log n) | O(n + m) | 已接受 |

 ## 算法演练

 1. 在图上运行基于 DFS 的寻桥算法（Tarjan low-link）以识别所有桥。 

这个想法是，如果 DFS 树中没有从 v 的子树到 u 的祖先的后边，则边 (u, v) 是一座桥。 
2. 构建一个新图，忽略所有非桥边。 

此时，图分裂成多个连通分量，每个连通分量都是 2 边连通的。 
3. 在非桥接边缘上使用 DFS/BFS 将组件 ID 分配给每个节点。 

同一组件中的每个节点都可以相互访问，而无需使用任何网桥。 
4. 仅使用桥边将图收缩为组件树。

每个桥恰好连接两个不同的组件，并且由于桥不形成循环，因此该结构是一棵树（森林，但原始图被连接，因此它成为一棵树）。 
5. 任意为该树求根并计算每个组件的深度。 
6. 使用二元提升在组件树上预先计算 LCA（最低共同祖先）结构。 
7. 对于每个查询 (s, l)，将两个端点映射到其组件并使用以下方法计算它们在树中的距离：

 深度[u] + 深度[v] - 2 * 深度[lca(u, v)]。 

这个距离的每个单位对应一座桥梁，因此也对应一条“重要道路”。 

### 为什么它有效

 正确性基于以下事实：收缩 2 边连接的组件后，每个剩余的边都是桥，并且该结构是非循环的。 两个原始节点之间的任何路径必须精确地经过连接其组件的桥边序列。 在组件内部，任何两个节点之间至少有两条不相交的路径，因此内部边缘对于分隔端点来说不是至关重要的。 因此，只有组件间的边很重要，并且它们形成一棵树，其中路径唯一性保证对组件路径上的边进行计数等于对不可避免的道路进行计数。 

## Python 解决方案```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

n, m = map(int, input().split())
g = [[] for _ in range(n)]

edges = []
for i in range(m):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    g[a].append((b, i))
    g[b].append((a, i))
    edges.append((a, b))

tin = [-1] * n
low = [-1] * n
timer = 0
is_bridge = [False] * m

def dfs(u, pe):
    global timer
    tin[u] = low[u] = timer
    timer += 1
    for v, idx in g[u]:
        if idx == pe:
            continue
        if tin[v] == -1:
            dfs(v, idx)
            low[u] = min(low[u], low[v])
            if low[v] > tin[u]:
                is_bridge[idx] = True
        else:
            low[u] = min(low[u], tin[v])

dfs(0, -1)

comp = [-1] * n
cid = 0

from collections import deque

for i in range(n):
    if comp[i] == -1:
        dq = deque([i])
        comp[i] = cid
        while dq:
            u = dq.popleft()
            for v, idx in g[u]:
                if comp[v] == -1 and not is_bridge[idx]:
                    comp[v] = cid
                    dq.append(v)
        cid += 1

cg = [[] for _ in range(cid)]

for i in range(m):
    if is_bridge[i]:
        a, b = edges[i]
        ca, cb = comp[a], comp[b]
        cg[ca].append(cb)
        cg[cb].append(ca)

LOG = 17
up = [[-1] * cid for _ in range(LOG)]
depth = [0] * cid

dq = deque([0])
vis = [False] * cid
vis[0] = True

while dq:
    u = dq.popleft()
    for v in cg[u]:
        if not vis[v]:
            vis[v] = True
            depth[v] = depth[u] + 1
            up[0][v] = u
            dq.append(v)

for i in range(1, LOG):
    for v in range(cid):
        if up[i-1][v] != -1:
            up[i][v] = up[i-1][up[i-1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for i in range(LOG):
        if diff & (1 << i):
            a = up[i][a]
    if a == b:
        return a
    for i in reversed(range(LOG)):
        if up[i][a] != up[i][b]:
            a = up[i][a]
            b = up[i][b]
    return up[0][a]

k = int(input())
out = []
for _ in range(k):
    s, t = map(int, input().split())
    s -= 1
    t -= 1
    cs, ct = comp[s], comp[t]
    w = lca(cs, ct)
    out.append(str(depth[cs] + depth[ct] - 2 * depth[w]))

print("\n".join(out))
```具有低链接值的 DFS 精确标记将循环与树状连接分开的边缘。 之后，非桥边上的 BFS 构建组件，确保每个组件最大程度地 2 边连接。 

收缩图仅从桥边构建，并且由于桥不能形成循环，因此它表现为树。 LCA结构是标准的二元提升，并且每个查询变成树距离计算。 

一个常见的实现陷阱是忘记在 DFS 中正确跳过父边，或者在处理后边时错误地将多个边标记为桥。 另一个微妙的点是，LCA必须建立在组件树上，而不是原始图上，否则会因循环而导致计数过多。

 ## 边缘情况

 一个重要的边缘情况是完全循环图，其中没有边是桥。 在这种情况下，每个节点都属于单个组件，因此所有查询都必须返回 0。该算法在组件形成期间将整个图折叠成一个节点，并且所有对的 LCA 距离都变为零。 

另一个例子是一棵树。 这里每条边都是一座桥，因此每个节点形成自己的组件。 桥树与原始图相同，并且 LCA 距离与节点之间的唯一路径长度完全匹配。 

最后一种情况涉及通过单个桥连接的多个周期。 例如，由一条边连接的两个三角形。 该单边成为桥树中唯一的桥，因此，如果端点位于不同的周期中，则任何跨越两个周期的查询都会返回 1，否则返回 0。 该算法正确地将每个三角形压缩为一个节点，并将连接桥保留为唯一的树边。
