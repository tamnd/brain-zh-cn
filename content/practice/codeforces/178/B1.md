 ## 解决方案
 ## 问题理解

 我们得到一个代表城市和道路的无向连通图。 每条道路都可以被移除，这可能会也可能不会破坏两个特定城市之间的连接。 除了图表之外，我们还看到了多个商家。 每个商人都有一个货物起始的源城市和货物必须到达的目的地城市。 

对于固定商家，我们考虑图中的所有道路。 如果删除单条道路导致无法从源头到达目的地，则对该商人计入一条道路。 用图的术语来说，对于一对顶点，我们计算它们之间的每条可能路径上有多少条边。 同样，我们计算的是相对于该特定对的桥梁边，这意味着它们对于这两个节点之间的连接是不可避免的。 

任务是为最多 100000 个商家独立计算此计数。 

这些约束立即排除了任何与边数呈线性关系的每商户图遍历。 每个查询的直接 DFS 或 BFS 将花费 O(n + m)，从而导致 O(k(n + m))，当所有查询都达到 10^5 时，这太大了。 

一个微妙的一点是，边缘可能对一对城市至关重要，但对另一对城市则无关紧要。 这意味着仅全局桥分解是不够的； 我们需要一个允许快速配对查询的结构。 

一个常见的陷阱是假设图中的所有桥都对其端点组件之间的每条路径都有贡献。 这是错误的。 仅当两个查询节点在桥树结构中被它分隔开时，桥才有意义。 

## 方法

 一种简单的方法是独立处理每个商家。 对于给定的对 (s, t)，我们逐条删除每条边，并使用 DFS 或 BFS 测试 s 和 t 之间的连通性。 每张支票的成本为 O(n + m)，因此每个商家的成本为 O(m(n + m))，这太大了。 

我们通过观察图可以被压缩为其桥接组件来改进这一点。 如果我们将每个最大 2 边连接组件收缩为单个节点，则生成的结构是一棵树，通常称为桥树。 该树中的每条边都对应于原始图中的一座桥，并且原始图中两个顶点之间的任何简单路径都对应于该树中其组件代表之间的唯一路径。 

现在关键的想法变得清晰了。 一条道路对于商人来说很重要，当且仅当它是一座位于桥树中 s 和 t 组成部分之间唯一路径上的桥。 因此，每个查询的答案就是该树路径上的边数。 

为了有效地回答这些路径长度查询，我们计算桥树上的最低公共祖先。 每个查询都简化为计算树中两个节点之间的距离，这可以使用深度和 LCA 预处理来完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的暴力破解 | O(k·m(n + m)) | O(k·m(n + m)) | O(n + m) | 太慢了|
 | 桥分解+LCA | O((n + m) + k log n) | O(n + m) | 已接受 |

 ## 算法演练

 1. 运行基于 DFS 的寻桥算法（Tarjan 风格）来识别图中的所有桥。 

这个想法是计算发现时间和低链接值，以便我们可以检测不位于任何循环上的边缘。 
2. 构建一个新图，其中每个 2 边连接的组件都收缩为单个节点。 

如果两个原始节点不通过任何桥连接，则它们属于同一组件。 
3. 每个桥连接两个不同的组件，因此我们使用这些桥边在组件上形成一棵树。

该结构是非循环的，因为移除桥就消除了所有循环。 
4. 任意根桥树并计算二进制提升 LCA 的深度和父指针。 
5. 对于每个商家，将其源城市和目的地城市映射到其组件标识符。 
6. 对于查询 (u, v)，计算它们在桥树中的 LCA，并使用树距离公式来获取它们之间的边数。 
7. 输出该距离作为该商人的关键道路数量。 

### 为什么它有效

 在任何 2 边连接的组件内，删除单个边不会断开任何两个节点，因此内部边不会被视为关键。 所有重要的边缘都是桥。 由于桥树是一棵树，因此任何两个组件之间都存在一条简单路径，并且该路径上的每条边都是不可避免的。 因此，对桥树中路径上的边进行计数相当于对删除会断开商家端点的边进行计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
g = [[] for _ in range(n)]

edges = []
for i in range(m):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    g[a].append((b, i))
    g[b].append((a, i))
    edges.append((a, b))

tin = [-1] * n
low = [-1] * n
timer = 0
is_bridge = [False] * m

def dfs(v, pe):
    global timer
    tin[v] = low[v] = timer
    timer += 1
    for to, eid in g[v]:
        if eid == pe:
            continue
        if tin[to] == -1:
            dfs(to, eid)
            low[v] = min(low[v], low[to])
            if low[to] > tin[v]:
                is_bridge[eid] = True
        else:
            low[v] = min(low[v], tin[to])

dfs(0, -1)

comp = [-1] * n
cid = 0

from collections import deque

for i in range(n):
    if comp[i] == -1:
        cid += 1
        q = deque([i])
        comp[i] = cid - 1
        while q:
            v = q.popleft()
            for to, eid in g[v]:
                if comp[to] == -1 and not is_bridge[eid]:
                    comp[to] = cid - 1
                    q.append(to)

tree = [[] for _ in range(cid)]
for i in range(m):
    a, b = edges[i]
    ca, cb = comp[a], comp[b]
    if ca != cb:
        tree[ca].append(cb)
        tree[cb].append(ca)

LOG = (cid).bit_length()
up = [[-1] * cid for _ in range(LOG)]
depth = [-1] * cid

def dfs2(v, p):
    up[0][v] = p
    for to in tree[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        dfs2(to, v)

for i in range(cid):
    if depth[i] == -1:
        depth[i] = 0
        dfs2(i, -1)

for j in range(1, LOG):
    for i in range(cid):
        if up[j-1][i] != -1:
            up[j][i] = up[j-1][up[j-1][i]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    j = 0
    while diff:
        if diff & 1:
            a = up[j][a]
        diff >>= 1
        j += 1
    if a == b:
        return a
    for j in range(LOG - 1, -1, -1):
        if up[j][a] != up[j][b]:
            a = up[j][a]
            b = up[j][b]
    return up[0][a]

def dist(a, b):
    c = lca(a, b)
    return depth[a] + depth[b] - 2 * depth[c]

k = int(input())
for _ in range(k):
    s, t = map(int, input().split())
    s -= 1
    t -= 1
    print(dist(comp[s], comp[t]))
```实现首先使用标准低链路 DFS 识别所有网桥。 关键的细节是，只有在 DFS 时间中严格增加分离的边才能成为桥梁。 之后，我们仅使用非桥边来洪水填充组件，确保每个组件相对于 2 边连接性而言是最大的。 

一旦构建了组件，我们就显式地构建桥树。 因为每个桥都连接两个不同的组件，所以这个结构保证是一个森林，并且由于原始图是连接的，所以它变成了一棵树。 

然后我们在这棵树上预处理二进制提升表。 每个查询都成为一个最低公共祖先计算，后跟一个距离公式。 正确性取决于以下事实：每条关键道路都对应于该树路径上的唯一边缘。 

一个微妙的实现细节是在预处理期间处理断开的 DFS 树。 即使原始图已连接，桥树仍然以每个组件森林遍历为根，因此我们为每个未访问的组件仔细初始化深度。 

## 工作示例

 ### 示例 1

 输入图结构是具有几个分支的链状主干，查询要求跨该结构的不同部分的距离。 

| 步骤| s 比较 | t 比较 | 生命周期评估 | 深度 | 深度(t) | 答案|
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 2 | 1 | 2 | 2 | 2 |
 | 2 | 1 | 2 | 1 | 1 | 2 | 1 |
 | 3 | 1 | 3 | 0 | 1 | 3 | 2 |

 该轨迹显示了答案如何与压缩树中的距离（而不是原始图中的距离）精确对应。 

### 示例 2

 考虑一个图表，其中多个周期分解为单个组件。 

| 步骤| s 比较 | t 比较 | 生命周期评估 | 深度 | 深度(t) | 答案|
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 0 | 1 | 1 | 0 |
 | 2 | 0 | 2 | 0 | 1 | 3 | 2 |
 | 3 | 2 | 4 | 1 | 3 | 4 | 3 |

 这证实了内部循环边缘永远不会对答案做出贡献，只有组件间的桥才能做出贡献。

 ## 边缘情况

 关键的边缘情况是根本没有桥的图，例如单个循环。 在这种情况下，所有节点都属于一个组件，因此每个查询都映射到桥树中的同一节点。 LCA 等于两个端点且距离为零，这符合没有道路单独关键的事实。 

另一种情况是树形图。 这里每条边都是一座桥，因此桥树与原始图相同。 该算法简化为标准树距离查询，并且两个节点之间的唯一路径上的每条边都被正确计数。 

最后一种情况是源和目标位于同一个 2 边连接组件中。 组件压缩将两者映射到同一节点，立即产生零，这正确地反映了没有单个边缘删除将它们断开。
