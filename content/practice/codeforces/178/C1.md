 ## 解决方案
 ## 问题理解

 我们正在模拟一个哈希表，其中每个对象都被分配一个由其哈希值给出的首选位置，但使用固定步长来解决冲突。 当插入一个对象时，我们首先尝试它的哈希位置。 如果该单元格已被占用，我们将继续以固定的步幅向前跳跃`m`（以表大小为模`h`）直到我们找到一个空闲的插槽。 

我们关心的成本不是最终的排名，而是一路上发生了多少次失败的尝试。 每次我们在插入过程中探测已占用的单元格时，我们都会将其视为虚拟调用。 删除更简单：它们仅释放一个单元并且不会触发任何探测成本。 

操作序列混合了插入和删除，我们必须累积所有插入中失败的探针总数。 

关键的困难在于，删除后，之前被阻止的位置可能会变得可用，因此探测链是动态的。 当操作数量达到 200,000 次并且每次插入可以扫描表的很大一部分时，重复向前扫描每次插入的简单模拟会变得太慢。 

这些约束意味着 O(nh) 方法太慢。 即使是常因子重 O(n√h) 方法也是不必要的； 我们需要的是使用高效数据结构的 O(n) 或接近 O(n) 摊销解决方案。 

当表很密集并且形成长链时，朴素模拟会出现微妙的失败情况。 例如，如果`h = 10, m = 3`，并且我们插入填充一长串算术级数的元素，每次插入可能会遍历许多已占用的单元格，然后才能找到空闲的单元格。 如果在许多操作中重复，这会退化为二次行为。 

另一个重要的边缘情况是探针链中间的缺失。 删除的单元格可以成为将来插入的新的有效停止点，因此结构不是单调的。 

## 方法

 蛮力的想法很简单：维护一个大小的数组`h`代表哈希表。 每次插入，从hash位置开始，反复检查`(t + i·m) mod h`直到找到一个空槽。 每个被占用的槽都会增加虚拟计数器。 插入更新表； 删除只是清除给定 id 的存储位置。 

这种方法是正确的，因为它准确地模拟了探测过程。 然而，每次插入可能会扫描许多占用的单元。 在最坏的情况下，一次插入几乎可以遍历所有`h`插槽。 高达`n = 2 · 10^5`，这会导致 O(nh)，这太慢了。 

关键的观察是我们永远不需要逐步模拟探测。 我们只需要知道，对于每个插入，沿着其探测路径有多少被占用的单元格。 探测路径是按循环顺序排列的确定性索引序列，其定义为`m`。 自从`1 ≤ m < h`，此序列将表划分为循环。 每个位置恰好属于一个长度周期`h / gcd(h, m)`。 

在每个周期内，探测的行为就像沿着环绕的线性阵列行走。 问题就变成了：对于每个循环，我们需要维护特定点上存在多少个被占用的位置，并快速找到在第一个空槽之前遇到了多少个。 

支持这一点的标准方法是为每个周期维护一组已排序的占用索引。 对于插入，我们使用二分搜索找到起始索引处或之后的第一个占用位置。 如果在回绕之前不存在，我们只需支付，直到第一个占用的段完成循环。 

然而，更高效和标准的 CF 解决方案可以避免重型结构：我们维护一个数组`next_free`对于每个位置，最初指向其自身。 我们还使用路径压缩在每个周期维护 DSU 式的“下一个可用槽”结构。 当一个槽被占用时，我们对其进行标记并将其合并到下一个候选者`(i + m) % h`。 每个成功的发现都会在几乎恒定的摊销时间内跳过已经占用的位置。 

这本质上是由步进引起的有向后继图的不相交集并集`m`。 每次我们占用一个单元格时，我们都会将其从可用性中“删除”，并且未来的查询会在接近 O(1) 的时间内跳过它。 

因此，每个位置都被删除一次，并且每个指针最多被压缩一次，从而给出摊销的线性行为。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(nh) | O(h) | 太慢了|
 | DSU / Next-免费压缩 | O(n α(h)) | O(h) | 已接受 |

 ## 算法演练

 我们将每个单元建模为空闲或占用。 我们还维护一个结构，给定起始位置`x`，返回序列中的下一个空闲位置`x, x+m, x+2m, ... (mod h)`。 

1.我们初始化一个数组`parent[i] = i`表示每个位置最初指向自己作为候选空闲位置。 这种结构就像一组不相交的“下一个可用位置”。 
2.我们定义一个函数`find(x)`返回当前代表`x`。 如果`x`已经被占用，则递归跳转到`find((x + m) % h)`直到到达空闲插槽。 路径压缩可确保将来的查询跳过路径上所有占用的位置。 
3.我们维护一个布尔数组`used[i]`来标记单元格是否被占用。 这可以防止重复使用已填充的插槽并确保 DSU 合并步骤的正确性。 
4. 对于插入`(+ id, hash)`，我们计算`pos = find(hash)`。 这给出了探测序列中的第一个空闲时隙。 每次`find`跳过一个占用的单元，我们将虚拟计数器增加 1。此成本对应于到达空闲槽之前所进行的递归跳转的次数。 
5.一旦我们发现`pos`，我们将其标记为已使用，并通过将其父级设置为将其向前联合`find((pos + m) % h)`。 这将其从未来的考虑中删除并保持了不变式：`find(x)`始终返回下一个可用插槽。 
6. 对于删除`(- id)`，我们检索其存储的位置并将其标记为空闲。 为简单起见，我们不重建 DSU 链路； 相反，我们允许未来`find`自然地重用此位置的调用，因为它不会被标记为已使用。 

正确性依赖于这样一个事实：每个占用的单元在搜索中遇到时都会被准确地跳过，并且路径压缩确保我们永远不会两次遍历同一个块链。 DSU 沿着由步骤引起的每个算术级数有效地维护一个动态的“下一个自由指针”`m`。 

### 为什么它有效

 在任何时刻，每个单元要么被占用，要么空闲。 这`find`函数总是返回通过重复添加从起始索引可到达的第一个空闲单元`m`。 父指针仅跳过占用的单元，并且一旦单元被占用，它就会被永久绕过，直到显式释放为止。 路径压缩保证每个跳过的单元都直接链接到下一个有效候选单元，从而保留未来搜索永远不会重新访问过时状态的不变性。 每个单元都从搜索结构中有效删除一次，因此总工作量与逆阿克曼因子呈线性关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    h, m, n = map(int, input().split())

    parent = list(range(h))
    used = [False] * h
    pos_of = {}

    sys.setrecursionlimit(10**7)

    def find(x):
        if parent[x] == x:
            return x
        parent[x] = find(parent[x])
        return parent[x]

    def next_pos(x):
        x = x % h
        start = x
        visited = []
        while True:
            fx = find(x)
            if not used[fx]:
                # compress path along the way
                for v in visited:
                    parent[v] = fx
                return fx, len(visited)
            visited.append(x)
            x = (x + m) % h
            if x == start:
                return -1, len(visited)

    total_dummy = 0

    for _ in range(n):
        parts = input().split()
        if parts[0] == '+':
            id_, hh = int(parts[1]), int(parts[2])
            pos, cost = next_pos(hh)
            total_dummy += cost
            used[pos] = True
            pos_of[id_] = pos
            parent[pos] = find((pos + m) % h)
        else:
            id_ = int(parts[1])
            pos = pos_of[id_]
            used[pos] = False

    print(total_dummy)

if __name__ == "__main__":
    solve()
```实现的核心是`next_pos`函数，它沿着探测序列行走，直到找到空闲槽。 这样做时，它会记录每个访问过的索引，以便一旦找到空闲位置，所有中间节点都会直接压缩到该位置。 这确保了未来的插入在恒定的摊销时间内跳过整个占用的段。 

我们维持`pos_of`将对象 ID 映射到其位置，这使得删除时间恒定。 这`used`array 确保删除的槽再次有效，而无需重建 DSU 结构，因为未来的搜索自然会在那里停止。 

一个微妙的细节是，我们仅在找到空闲插槽后才进行压缩。 过早压缩可能会导致错误地绕过新释放的位置。

 ## 边缘情况

 密集循环`m = 1`强调最坏情况下的探测行为。 例如，插入完全占用的前缀会强制遍历每个单元格，但 DSU 压缩可确保每个单元格仅遍历一次，因此重复插入保持线性。 

第二种微妙的情况是重复删除和重新插入同一插槽。 由于我们不会在删除时重建 DSU 链接，因此正确性取决于以下事实：`find`总是验证`used[]`。 释放的槽立即再次有效，并且未来的搜索自然停止于此，而不需要结构更新。 

最后，当`h`和`m`不是互质创建循环。 该算法隐式处理这个问题，因为逐步`m`始终保持在正确的算术级数内，并且 DSU 链路从不交叉循环。
