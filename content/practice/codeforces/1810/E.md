 ## 解决方案
 ## 问题理解

 我们得到一个无向图，其中每个顶点都包含一个具有数字要求的怪物。 如果怪物有价值`a[i]`，只有当你至少已经击败过它时，你才可以击败它`a[i]`其他怪物。 

该过程从选择单个顶点开始`s`在哪里`a[s] = 0`，因为一开始你什么也没打败。 之后，您沿着边缘移动。 当你穿越到一个新的顶点时，你要么到达那里已经被击败，要么在到达的那一刻击败它的怪物，前提是你当前击败的怪物数量足够。 

一旦怪物被击败，它就保持被击败的状态，你可以自由地重新访问顶点。 

问题是是否存在一个起始顶点和一系列移动，使得每个怪物最终都能被击败。 

关键的困难在于，移动受到图连接性的限制，但击败节点的资格受到取决于访问顺序的不断增长的阈值条件的限制。 

约束条件很大，总共`n`和`m`跨测试用例最多`2 × 10^5`。 这立即排除了任何尝试模拟所有可能的访问节点顺序或为每个可能的启动运行 BFS/DFS 的解决方案。 我们需要具有仔细排序逻辑的线性或近线性图遍历。 

一些微妙的边缘情况很重要。 

如果没有有值的节点`0`，答案立即`NO`，因为我们甚至无法开始。 

如果零值节点存在，但以阻止到达其他组件的方式隔离，即使可以进行本地遍历，我们仍然可能会失败。 

更微妙的情况是，组件可到达，但包含度数非常小的顶点或孤立的结构，迫使过早访问高价值节点。 例如，在路径中，如果在收集足够的节点之前必须穿过高价值节点，则该过程将被阻塞。 

## 方法

 强力解释是尝试每个可能的起始顶点`a[i] = 0`，模拟遍历，并在强制约束的同时维护失败的节点集`defeated_count ≥ a[v]`当尝试进入节点时。 每个模拟都需要 BFS 或类似 DFS 的探索，其中可用的移动取决于当前状态。 

这会失败，因为状态空间是指数的。 访问节点的顺序很重要，简单的模拟可以有效地探索有效遍历顺序的排列。 即使是单个测试用例也可能需要探索`O(n!)`最坏情况下的订单。 

关键的观察是，移动规则和“失败阈值”一起意味着贪婪结构：如果一个节点在图意义上是可达的并且其要求当前可以满足，那么延迟它永远不会有帮助。 真正的限制不是路径顺序复杂性，而是我们是否能够保持不断增长的可达边界，在该边界中我们总是首先选择最小的可用需求。 

这建议按顶点排序`a[i]`值并逐步激活它们，但仅激活是不够的，因为连通性很重要。 我们需要确保当我们决定包含一个顶点时，它位于从某个有效起点已经可以到达的连接区域中。 

这导致了联合查找或基于 DSU 的想法：我们模拟按升序添加顶点`a[i]`。 在每一步中，我们激活要求≤当前“失败计数”的节点，并通过边将它们联合起来。 如果在任何时候所有活动节点形成单个连接组件并且我们可以继续增长直到包含所有节点，则该过程是可行的。 

更深层次的想法是，一旦我们确定了一个与非递减一致的顺序`a[i]`，图的连通性仅通过新激活的节点是否可以附加到已经可达的区域来影响。 如果在某个时刻，一个节点按值变得合格，但未连接到当前可达集，我们将被迫推迟它，这可能会阻碍未来的进展。 

因此，我们使用 DSU 和排序节点上的指针来跟踪可达性，并尽可能扩展。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n!) | O(n + m) | 太慢了 |
 | DSU + 按值贪婪激活 | O((n + m) log n) | O((n + m) log n) | O(n + m) | 已接受 |

 ## 算法演练

 1. 按值对所有顶点进行排序`a[i]`按递增顺序。 

这反映了唯一有意义的全局约束：我们永远不能早于其要求允许的时间击败节点，因此值顺序是自然的候选顺序。 
2. 初始化所有顶点的DSU结构，以及一个数组`active[i] = False`指示顶点当前是否包含在可达处理集中。 
3. 维护指针`i`在排序后的顶点和计数器上`done`代表有多少节点已被激活（到目前为止已被击败）。 
4、从有价值的节点开始`0`。 对于每个顶点`a[i] = 0`，激活它并将其与任何已经活跃的邻居联合。 这形成了初始可达区域。 
5. 现在反复尝试扩展：

 当有可能取得进展时，激活任何其顶点`a[v] ≤ done`并且它与当前活动组件相邻（在 DSU 意义上）。 每次我们激活一个顶点时，我们都会递增`done`并将其与活跃的邻居联合起来。 

这个条件很重要的原因是击败一个节点会增加`done`，因此只有已经满足要求的节点才能安全地包含在内。 
6. 如果在某个时刻没有新的顶点可以被激活，但仍然有不活动的顶点，则该过程被卡住。 返回`NO`。 
7. 如果所有顶点都变为活动状态，则返回`YES`。 

### 为什么它有效

 该算法维护一组不断增长的失败顶点，这些顶点始终满足每个包含节点的约束。 在满足要求之前，我们从不激活顶点，并且只激活通过边连接到已经可达的结构的顶点。 这确保了移动限制得到尊重：我们永远不会“传送”到不相连的区域。 如果进程停止，则意味着每个剩余的顶点要么需要太多已失败的节点，要么与当前可达集断开连接，因此任何有效的排序都无法包含它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        adj = [[] for _ in range(n)]

        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            adj[v].append(u)

        nodes = sorted(range(n), key=lambda x: a[x])

        dsu = DSU(n)
        active = [False] * n
        done = 0

        ptr = 0
        changed = True

        while changed:
            changed = False

            while ptr < n and a[nodes[ptr]] <= done:
                v = nodes[ptr]
                ptr += 1
                if active[v]:
                    continue

                active[v] = True
                done += 1

                for to in adj[v]:
                    if active[to]:
                        dsu.union(v, to)

                changed = True

        print("YES" if done == n else "NO")

if __name__ == "__main__":
    solve()
```该实现按难度值对顶点进行排序，然后贪婪地激活所有当前可行的顶点。 这`done`计数器跟踪到目前为止已经击败了多少怪物，这直接决定了哪些节点符合资格。 

DSU 用于维护激活节点之间的连接，尽管在此解决方案中，它的作用主要是确保每当我们激活节点时，它都会通过其活动邻居合并到当前可达结构中。 

一个微妙的点是我们只考虑按递增顺序的顶点`a[i]`，所以一旦我们跳过排序列表中的一个节点，我们就不会再访问它。 这是安全的，因为`done`只会增加，因此资格是单调的。 

## 工作示例

 ### 示例 1

 输入：```
4 3
2 1 0 3
1-2, 2-3, 3-4
```按值排序：节点 3 (0)、节点 2 (1)、节点 1 (2)、节点 4 (3)

 | 步骤| 完成 | 激活节点| 活动集|
 | ---| ---| ---| ---|
 | 1 | 0 | 3 | {3} |
 | 2 | 1 | 2 | {3,2} |
 | 3 | 2 | 1 | {3,2,1} |
 | 4 | 3 | 4 | {3,2,1,4} |

 所有节点都激活成功，所以答案是YES。 

该跟踪显示单调增长：一旦节点变得合格，它就永远不会被阻止，因为`done`只会增加。

 输入：```
4 3
0 1 2 0

```已排序：值为 0,0,1,2 的节点

 | 步骤| 完成 | 激活节点 | 活动集|

 | 1 | 0 | 1 | {1} |
 | 2 | 1 | 4 | {1,4} |
 | 3 | 2 | 2 | {1,4,2} |
 | 4 | 3 | 3 | {1,4,2,3} |

 在这里，两个零节点都充当独立的起点，随着资格的增加，连接性足以合并所有节点。

 ## 边缘情况

 关键的边缘情况是存在多个零值节点但位于单独的组件中。 仅当至少一个组件可以通过增加而增长时，该算法仍然成功`done`间接接触他人。 如果没有一个可以桥接组件，则激活在耗尽初始零区域后立即停止。 

另一种边缘情况是单个零节点未连接到所有其他节点。 即使其他节点的值很小，如果图结构阻止通过已经活跃的节点到达其激活链，则它们仍然无法访问，从而导致进程过早停止。
