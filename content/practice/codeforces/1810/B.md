 ## 问题理解

 我们从一颗糖果开始，想要准确地达到$n$最多使用 40 个咒语的糖果。 每个咒语要么使当前糖果数量加倍并减去一个，要么使当前糖果数量加倍并加一个。 输入由多个测试用例组成，每个测试用例给出一个目标数字$n$。 每个测试用例的输出是一系列达到$n$40 步以内或`-1`如果不可能的话。 

界限很紧但可以管理。 和$n$最多$10^9$并且允许 40 次操作，天真的暴力前向模拟是有风险的。 直接尝试所有序列是指数级的：有$2^{40}$可能的序列，远远超出我们的计算范围。 这意味着我们需要对序列进行数学推理或对其进行逆向工程。 

边缘情况是当$n$非常小，比如$n=2$。 对 1 颗糖果使用第一个咒语会给出$2 \cdot 1 - 1 = 1$- 没有进展。 使用第二个咒语给出$2 \cdot 1 + 1 = 3$，超调 2。因此，并非所有$n$是可达的，并且粗心的实现假设每个$n$isreachable 会错误地尝试构建一个序列$n=2$。 

另一个边缘情况是附近有大量数字$10^9$。 如果实现在向后跟踪时无法正确处理整数除法或减法，则可能会因截断错误而在大型目标上失败。 

## 方法

 蛮力方法会尝试从 1 到 40 步的所有可能的咒语序列，模拟每次前进。 这是有效的，因为每个咒语都是确定性的，并且总是会增加糖果的数量，所以我们最终会达到$n$或超过 40 步。 问题是序列的数量是$2^{40} \approx 10^{12}$，对于任何计算机来说都太大了。 

关键的洞察力来自于逆向工作。 如果我们有$n$糖果，我们问：哪个咒语可以产生$n$在上一步中？ 如果最后一个咒语是`1`(2x-1)，那么之前的糖果数量一定是$(n+1)/2$。 如果最后一个咒语是`2`(2x+1)，那么之前的糖果数量一定是$(n-1)/2$。 这两个都必须是整数。 重复这个推理可以让我们反向重建咒语序列。 

向后工作可以保证每一步都是有效的，因为它直接匹配咒语的逆过程。 由于我们在到达 1 颗糖果时停止，因此我们会自动确保序列正确开始。 如果在任何时候后向数不是整数或负数，我们就知道到达$n$是不可能的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^40) | O(2^40) | O(40) | 太慢了 |
 | 逆向构造| O(40) | O(40) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，读取目标编号$n$。 初始化一个空列表来存储咒语序列。 
2. 虽然$n > 1$，检查哪个咒语可以产生它。 如果$(n+1)$能被 2 整除，最后一个咒语可能是`1`。 附加`1`到顺序并更新$n = (n+1)//2$。 否则，如果$(n-1)$能被 2 整除，最后一个咒语可能是`2`。 附加`2`到顺序并更新$n = (n-1)//2$。 
3. 如果两个条件都不成立，则不可能达到$n$从1开始使用咒语。 输出`-1`。 
4.到达后$n=1$，颠倒顺序即可获得咒语从开始到结束的顺序。 
5. 输出序列的长度和序列本身。 如果序列超过 40 个咒语，也将其视为不可能。 

该算法之所以有效，是因为每一步都严格遵循拼写函数的反函数。 不变的是，在每次后退一步之后，当前的数字正是使用一个咒语产生下一个数字的数字。 这保证了正确性并避免猜测或前向模拟。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        spells = []
        original = n
        while n > 1:
            if (n + 1) % 2 == 0:
                spells.append(1)
                n = (n + 1) // 2
            elif (n - 1) % 2 == 0:
                spells.append(2)
                n = (n - 1) // 2
            else:
                spells = None
                break
        if spells is None or len(spells) > 40:
            print(-1)
        else:
            spells.reverse()
            print(len(spells))
            print(' '.join(map(str, spells)))

if __name__ == "__main__":
    solve()
```代码读取测试用例的数量，然后迭代每个目标$n$。 通过使用整数除法向后工作，它可以反向重建拼写序列。 颠倒顺序即可得到正确的正向顺序。 该算法显式检查超过 40 步的序列并输出`-1`当不可能的时候。 边缘情况如$n=2$自然处理，因为两者都没有$(2+1)/2$也不$(2-1)/2$是减至 1 的整数。

 ## 边缘情况

 对于`n=2`，算法检查`(2+1)/2=1.5`和`(2-1)/2=0.5`。 两者都不是整数，因此算法输出`-1`。 这可以防止无效序列。 

为了`n=1`，不需要咒语。 该算法自然会产生一个长度为 0 的空序列。 

对于非常大的`n`，每向后退一步大约减半，确保我们永远不会超过 40 步。 例如，`n=10^9`每一步大约减少 2 倍，大约为 30
