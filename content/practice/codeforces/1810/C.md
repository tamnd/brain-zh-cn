 ## 解决方案
 ## 问题理解

 我们得到一个数组和两个具有固定成本的操作。 

为了节省成本，我们可能会删除任何现有元素`c`，或插入任何正整数作为成本`d`。 

目标是将数组转换为某个长度的有效排列`m`。 长度的排列`m`包含来自的每个数字`1`通过`m`正好一次。 顺序并不重要，因为我们可以将元素保留在当前位置，并在任何位置插入新值。 

任务是找到最小的总成本。 

最重要的观察是最终的排列完全由其最大值决定。 如果最终的排列有长度`m`，那么最终的值集必须准确无误`{1, 2, ..., m}`。 

约束足够大，二次解是不可能的。 所有数组长度之和最多为`2·10^5`，这强烈表明`O(n log n)`每个测试用例的解决方案，以排序为主。 任何尝试每个子集或重复扫描整个数组以查找每个候选长度的方法都会超出限制。 

一些边缘情况很容易被错误处理。 

考虑：```
n = 3
a = [1, 1, 1]
c = 5
d = 100
```正确答案是`10`，通过删除两个副本并保留一个来获得`1`，产生排列`[1]`。 

粗心的解决方案可能会尝试构建更大的排列并不必要地付出巨大的插入成本。 

另一个棘手的情况是：```
n = 2
a = [100, 100]
c = 1
d = 1
```最好的策略是删除一个`100`，删除其他的`100`，然后插入`1`，总成本`3`。 

保留大值是没有用的，因为任何长度排列`m`不能包含大于的数字`m`。 

重复项需要特别小心：```
n = 4
a = [1, 2, 2, 3]
c = 10
d = 1
```正确答案是`10`，删除一个重复项`2`。 

如果不首先删除重复项，对缺失值进行天真的计数会产生错误的结果，因为排列要求每个值都恰好出现一次。 

## 方法

 暴力的观点是选择最终的排列长度`m`。 

一次`m`是固定的，每个数组元素大于`m`必须被删除。 值来自`1`到`m`，每个只能保留一份副本。 必须插入缺失值。 我们可以计算每种可能的成本`m`并取最小值。 

困难在于`m`可能非常大。 由于数组值达到`10^9`，直接检查所有可能的长度是不可能的。 

关键的观察是，只有数组中已经存在的值才能有意义地充当最大保留值。 

假设我们对数组进行排序并从概念上删除重复项。 令不同的值为：```
v1 < v2 < ... < vk
```如果我们决定`vi`是最终排列中保留的最大值，然后之后的每个不同值`vi`必须删除。 

其中第一`i`不同的值，我们只保留每个值的一份副本。 使它们成型`{1,2,...,vi}`，我们必须在下面插入所有缺失的数字`vi`。 

缺失值的数量为：```
vi - i
```因为应该有`vi`中的数字`{1,...,vi}`，但仅`i`目前那里存在不同的价值观。 

这将问题转化为根据不同值评估一个候选者。 

还有一种特殊情况，我们删除所有内容并构建排列`[1]`。 由于最终数组必须非空，因此成本为：```
n * c + d
```删除所有原始元素，然后插入`1`。 

排序后，我们可以从左到右扫描不同的值，同时维护已经处理了多少元素。 然后可以在恒定的时间内对每个候选人进行评估。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解所有可能的长度 | O(max(a)) 或更糟 | O(1) | O(1) | 太慢了 |
 | 对具有独特价值的候选人进行排序和评估 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对数组进行排序。 
2. 用删除每个元素并插入单个元素的成本来初始化答案`1`。```
ans = n*c + d
```这保证了至少一个有效的解决方案。 
3. 扫描已排序的数组并仅处理每个不同值的第一次出现。 
4.让`cnt`是迄今为止处理的不同值的数量。 
5. 当达到新的独特值时`x`， 对待`x`作为最终排列中保留的最大值。 
6. 范围内缺失值的数量`[1, x]`是：```
missing = x - cnt
```因为有`cnt`不同的保留值，但排列结束于`x`准确地要求`x`价值观。 
7. 当前位置之后的每个元素都必须删除。 如果当前索引是`i`在排序后的数组中，则：```
deletions = n - i - 1
```这些都是严格位于右侧的元素，包括重复项和较大的值。 
8. 该候选人的总成本为：```
deletions*c + missing*d
```9. 更新最低答案。 
10. 继续，直到处理完所有不同的值。 
11. 输出找到的最小成本。 

### 为什么它有效

 排序后，考虑任何最佳的最终排列。 设其最大保留原值为`x`。 

每个值大于`x`必须删除，因为长度的排列`x`无法容纳他们。 保留值中的每个重复项也必须删除。 扫描自然地通过仅保留每个不同数字的第一次出现来解释这一点。 

不同值之间不超过`x`， 确切地`cnt`价值观已经存在。 有效的排列`{1,...,x}`需要全部`x`值，所以确切地说`x-cnt`必须插入数字。 没有其他插入计数可以工作。 

因此，每个可能的最佳解决方案都对应于选择一些不同的值`x`作为最大保留值，算法会评估该选择的确切成本。 由于检查了所有候选者，因此找到的最小成本是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, c, d = map(int, input().split())
        a = list(map(int, input().split()))

        a.sort()

        ans = n * c + d

        cnt = 0

        for i in range(n):
            if i > 0 and a[i] == a[i - 1]:
                continue

            cnt += 1

            missing = a[i] - cnt
            deletions = n - i - 1

            cost = deletions * c + missing * d
            ans = min(ans, cost)

        print(ans)

solve()
```首先对数组进行排序，以便重复项变得相邻，并且较大的值出现在较小的值之后。 

变量`cnt`计算遇到的不同值的数量。 当当前的不同值是`a[i]`，我们想象保留迄今为止看到的所有不同的价值观，并使`a[i]`最终排列中的最大值。 

表达式：```
missing = a[i] - cnt
```计算有多少个数字`1`到`a[i]`缺席。 

表达式：```
deletions = n - i - 1
```计算右侧的每个元素。 这些元素不能保留，如果`a[i]`选择作为最大保留值。 

一个微妙的点是初始化：```
ans = n * c + d
```这表示删除所有内容并插入一个`1`。 如果没有这个候选项，所有现有值都极大的情况将被错误处理。 

Python 整数会自动处理达到问题限制的值，因此不存在溢出问题。

 ## 边缘情况

 考虑：```
1
3 5 100
1 1 1
```该算法评估不同值`1`。```
cnt = 1
missing = 0
deletions = 2
cost = 10
```答案就变成了`10`，相当于删除两个重复项并保留一个`1`。 自动避免昂贵的插入。 

考虑：```
1
2 1 1
100 100
```独特的候选人是`100`。```
missing = 99
deletions = 1
cost = 100
```初始化给出：```
2*1 + 1 = 3
```哪个更小。 该算法正确地选择删除所有内容并创建`[1]`。 

考虑：```
1
4 10 1
1 2 2 3
```对于候选人`3`：```
cnt = 3
missing = 0
deletions = 1
cost = 10
```唯一需要采取的行动是删除多余的`2`。 由于在不同值扫描期间会跳过重复项，因此计算完全符合所需的成本。 

这些案例说明了三个常见的陷阱：重复、非常大的值以及从头开始重建比保留现有元素更便宜的可能性。
