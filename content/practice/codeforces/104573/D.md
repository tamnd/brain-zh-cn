 ## 解决方案
 ## 问题理解

 我们给出了一系列敌人，每个敌人都有一定的生命值，以及一个具有初始生命值的生物。 目标是决定她是否能够按顺序击败所有敌人，同时确保自己的生命值永远不会降至零或更低。 

有两种攻击选择。 一种是强力攻击，每个敌人最多可以使用一次，造成高伤害，但也会消耗大量生命值。 另一种是较弱的攻击，可以无限次使用，每次使用造成的伤害较小，并且每次使用也会消耗一些生命值。 

关键的难点在于每个敌人的生命值必须降至零，并且我们可以混合使用两种攻击类型。 这个决定不仅仅是针对每个敌人的本地决定，因为过早消耗过多的生命值可能会使以后的战斗变得不可能。 因此，问题在于如何最大限度地减少自我伤害，同时仍然确保彻底击败每个敌人。 

限制最多为 100,000 个敌人，因此任何尝试针对每个敌人的攻击分配的所有组合的解决方案都是不可能的。 即使对每个敌人进行二次推理也会太慢，因此我们需要对每个敌人进行贪婪或算术决策。 

一个常见的陷阱是独立对待每个敌人，并始终使用“单位成本的最佳伤害”攻击。 但这会失败，因为强力攻击仅限于每个敌人一次，并且可能会浪费在效率不高的小敌人身上，即使在局部看起来不错。 

另一个微妙的问题是忘记了部分使用弱攻击必须完全耗尽剩余生命值，因此一次强击后剩余的生命值仍然需要足够的弱攻击，而这总体上来说成本很重要。 

## 方法

 暴力方法会尝试为每个敌人分配攻击类型：对于每个敌人，决定使用多少次弱攻击以及是否应用强攻击。 这导致了指数级的可能性，大致$2^M$，因为每个敌人都有多种使用模式组合。 即使将每个敌人减少为“强使用或不使用”也是不够的，因为弱攻击的数量仍然是可变的。 

一旦 M 增长到超过 30 或 40，这很快就变得不可行。 

关键的观察是，对于每个敌人，我们只关心击败它所需的最小可能的自我伤害。 由于敌人的生命值要求是独立的（除了剩余生命值之外没有任何结转状态），我们可以为每个敌人计算将其生命值降低到零的最便宜的方法，然后将这些成本相加。 

对于给定的敌人，我们比较两种策略：仅使用弱攻击，或使用一次强攻击，然后使用足够的弱攻击来完成剩余的生命值。 我们选最便宜的。 一旦每个敌人都减少了成本，我们只需从初始生命值中减去总成本即可。 

这将问题变成了简单的累积检查。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(1)-O(M) | O(1)-O(M) | 太慢了 |
 | 最佳| O(M)| O(1) | O(1) | 已接受 |

 ## 算法演练

 让每个敌人都有生命值$a_i$。 

1. 对于每个敌人，计算需要多少次弱攻击才能完全击败它。 每次弱攻击都会造成$Q_1$损害和费用$Q_2$HP，所以弱攻击次数为$\lceil a_i / Q_1 \rceil$。 这给出了仅弱策略的总成本：$cost_weak = \lceil a_i / Q_1 \rceil \cdot Q_2$。 
2. 如果我们使用一次强力攻击，就会减少敌人$P_1$。 如果$a_i \le P_1$，那么一次强力攻击就足够了，成本就是$P_2$。 
3.否则强击后剩余生命值$a_i - P_1$。 我们还需要$\lceil (a_i - P_1) / Q_1 \rceil$弱攻击，因此成本变为$cost_strong = P_2 + \lceil (a_i - P_1) / Q_1 \rceil \cdot Q_2$。 
4. 对于每个敌人，采取$min(cost_weak, cost_strong)$作为所需的最小 HP 损失。 
5. 将所有敌人的所有这些最小成本相加。 
6.如果初始HP$N$严格大于总成本，输出“YES”，否则输出“NO”。 

对每个敌人采取最小值的原因是，除了共享生命值预算外，敌人之间没有相互作用，因此最优的全局策略分解为最优的局部选择。 

### 为什么它有效

 每个敌人的伤害要求都是独立的，每个有效的策略都必须将其生命值完全降至零。 对于任何固定的敌人，任何行动序列都可以重新安排为“全是弱攻击”或“先强攻击后弱攻击”，而不会增加成本，因为不允许进行额外的强攻击，而弱攻击的成本是线性的。 因此，每个敌人的最小成本相加后就是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    P1, P2 = map(int, input().split())
    Q1, Q2 = map(int, input().split())
    a = list(map(int, input().split()))

    total = 0

    for hp in a:
        weak_hits = (hp + Q1 - 1) // Q1
        cost_weak = weak_hits * Q2

        if hp <= P1:
            cost_strong = P2
        else:
            rem = hp - P1
            weak_after = (rem + Q1 - 1) // Q1
            cost_strong = P2 + weak_after * Q2

        total += min(cost_weak, cost_strong)

    print("YES" if total < N else "NO")

if __name__ == "__main__":
    solve()
```该解决方案读取所有参数，然后迭代每个敌人，计算击败它的最便宜的方法。 关键的实现细节是计算弱攻击计数时仔细的上限划分。 这两种策略都经过明确计算，以避免在强攻击超出或完全匹配剩余 HP 的边缘情况下出现推理错误。 

最终比较使用严格的不等式，因为 Iggy 必须严格保持在零 HP 之上。 

## 工作示例

 ### 示例 1

 输入：```
N = 8, M = 3
P1 = 5, P2 = 2
Q1 = 3, Q2 = 1
a = [5, 8, 6]
```我们计算每个敌人：

 | 敌人| 成本疲软| 成本强劲| 选择|
 | --- | --- | --- | --- |
 | 5 | 天花板(5/3)=2 → 2 | P2=2 | 2 |
 | 8 | 天花板(8/3)=3 → 3 | 2 + 天花板(3/3)=1 → 3 | 3 |
 | 6 | 天花板(6/3)=2 → 2 | 2 + ceil(1/3)=1 → 3 | 2 |

 总成本 = 2 + 3 + 2 = 7。 

剩余 HP = 8 − 7 = 1，因此输出为 YES。 

这个痕迹表明，强力攻击并不总是有利的； 这取决于相对于弱攻击效率的剩余生命值。 

### 示例 2

 输入：```
N = 10, M = 2
P1 = 4, P2 = 5
Q1 = 2, Q2 = 3
a = [3, 7]
```敌人1：

 弱 = ceil(3/2)=2 → 6

 强 = 5（因为 3 <= 4）→ 选择 5

 敌人2：

 弱 = ceil(7/2)=4 → 12

 强 = 5 + ceil(3/2)=2 → 11 → 选择 11

 总计 = 5 + 11 = 16。 

剩余生命值 = 10 − 16 ≤ 0，所以答案是否定的。 

由此可见，即使使用强力攻击，累计消耗依然会超过初始生命值，导致无法取得结果。

 ## 边缘情况

 当敌人的生命值恰好可以被弱攻击伤害整除时，就会出现一个关键的边缘情况。 这样的话，上限分割就等于精确分割，不会有浪费的攻击。 该算法自然地处理这个问题，因为整数上限除法`(hp + Q1 - 1) // Q1`折叠到`hp / Q1`。 

当强力攻击将 HP 降低到恰好为零时，会出现另一种边缘情况。 代码通过条件来处理这个问题`hp <= P1`，确保之后不会添加弱攻击，从而防止产生差一的额外成本。 

最后，当两种攻击类型都极其低效时，即使 M 很小，总成本也可能超过 N，并且算法在比较之前正确聚合所有每个敌人的成本，而不是做出早期决策。
