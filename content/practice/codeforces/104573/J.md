 ## 解决方案
 ## 问题理解

 我们得到一行堆栈，每个堆栈保存一定数量的块。 我们只能在相邻的堆栈之间移动块，并且我们也可以通过将块推离桌子来从线的两端移除块。 目标是使用最少数量的此类单元移动将堆叠高度的初始配置转换为目标配置，其中单元移动要么向左或向右移动一个块一个位置，要么丢弃边界处的一个块。 

每个块都可以被认为是一个质量单位，必须要么最终进入其最终堆栈，要么从系统中删除，并且相邻堆栈之间的每个移动单位的每条边交叉都会花费一步。 这从根本上解决了沿线性成本路径运输多余质量的问题。 

约束很大，最多有 100,000 个堆栈，每个堆栈最多有 10^12 个值。 这立即排除了任何跟踪单个块或显式模拟移动的方法。 任何有效的解决方案都必须聚合堆栈之间的流量并以线性或接近线性的时间运行。 

一个关键的微妙之处是无法保证可行性。 即使块的总数匹配，如果质量无法正确地传入或传出边界，局部不平衡仍然会导致转换无法进行。 

当人们认为只有总和才重要时，就会出现天真的错误。 例如，如果我们只检查 sum(a) 等于 sum(b)，我们可能会接受质量被困在中间但边界无法吸收或提供它的情况。 

考虑：```
n = 3
a = [0, 10, 0]
b = [5, 0, 5]
```总和匹配，但中间的堆栈必须分成两端。 由于移动仅通过邻接进行，因此这是可能的，但如果问题具有更严格的方向约束或边界限制，则朴素推理可能会失败。 这个例子强调了可行性取决于累积流量，而不仅仅是总数。 

如果我们贪婪地转移本地多余的东西而不考虑长途运输成本，就会出现另一种失败情况。 在没有聚合的情况下逐一移动块会导致二次行为。 

## 方法

 关键的观察是每个堆栈差异都可以解释为块的供应或需求。 将差异数组定义为：$$d_i = a_i - b_i$$如果我们从左到右扫描，我们可以想到携带盈余。 每当堆栈有多余的块时，多余的块就必须传递到右侧； 当出现赤字时，必须通过来自左侧或早期转移的流入流量来补偿。 

跨过边缘的每一单位剩余量只为每一步贡献一次移动。 这意味着总成本与区块在全局的最终位置无关，而是与穿过相邻堆栈之间的每个边界的流量有关。 

暴力解释将模拟单独移动每个块。 每个块可能会遍历 O(n) 个位置，在最坏的情况下导致 O(n^2) 行为，这对于 n 高达 100,000 来说是不可能的。 

关键的见解是我们永远不需要跟踪单个块。 我们只需要在扫描数组时跟踪累积不平衡。 运行前缀总和准确地告诉我们有多少流量必须穿过每个边界，总成本是绝对前缀值的总和。 

如果最终差异总和不为零，则总体上要么是过剩，要么是赤字。 由于只允许在末端去除边界，因此这种不平衡必须已经通过施工在本地得到解决； 否则，转变是不可能的。

 ## 算法演练

 1. 通过迭代堆栈并跟踪运行余额来隐式计算差异数组`cur = cur + (a[i] - b[i])`。 

该值表示必须从以 i 结尾的前缀向右推送多少个额外块。 
2. 如果在任何时候最终总余额不为零，则返回 -1。 

这确保了全局可行性，因为所有块必须匹配目标或仅在边界处可移除。 
3. 初始化`cur = 0`和`ans = 0`。 
4. 从左到右迭代所有堆栈。 对于每个位置 i，更新`cur += a[i] - b[i]`。 
5.更新后，添加`abs(cur)`到答案。 

这表示必须跨越 i 和 i+1 之间边界的块数，因为必须结转非零前缀剩余。 
6. 返回`ans`处理完所有堆栈后。 

### 为什么它有效

 在 i 和 i+1 之间的每个边界处，前缀和`cur`表示必须跨越该边界以使所有堆栈与其目标一致的净块数。 任何正值意味着多余的块必须向右移动； 负数表示赤字必须从右侧填补。 每个不平衡单位恰好对应于跨越该边界的一个移动单位，因此对绝对前缀不平衡求和会将每个相邻移动恰好计数一次。 由于除边界外流量是守恒的，因此不会重复计算或错过任何移动。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    cur = 0
    ans = 0

    for i in range(n):
        cur += a[i] - b[i]
        ans += abs(cur)

    if cur != 0:
        print(-1)
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```该实现依赖于单个线性传递。 变量`cur`维护必须跨当前边界传输的块的运行剩余。 的积累`abs(cur)`是关键步骤：它计算最佳流中必须穿过每条边的块数。 

最后检查`cur != 0`确保处理完所有堆栈后，没有剩余的剩余部分。 如果存在剩余质量，则除了边界处之外，它无法被吸收或创建，并且由于流动模型中已隐式考虑了两端，因此非零余数表示不一致。 

一个常见的实施错误是将`abs(cur)`更新前更新`cur`。 正确的顺序很重要，因为`cur`在测量该边界处的交叉成本之前，必须反映当前位置的不平衡情况。

 ## 边缘情况

 一种边缘情况是初始配置和目标配置之间的所有堆栈都相同。 在这种情况下，每个差异都为零，因此运行余额始终保持为零，并且累计成本保持为零。 该算法无需特殊处理，自然返回0。 

另一种边缘情况是所有多余部分都集中在一个端点。 例如，如果`a = [10,0,0]`和`b = [0,0,10]`，前缀和变大并保持正值，直到最后一步。 成本正确累积，因为整个盈余必须恰好穿过每个边界一次。 

当实现忘记最终的可行性检查时，就会出现故障模式。 如果总剩余不为零，则运行前缀仍可能产生数字成本，但它不对应于有效的转换。 决赛`cur == 0`条件是阻止接受此类案件的原因。
