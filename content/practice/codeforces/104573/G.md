 ## 解决方案
 ## 问题理解

 我们得到一个有向图，其中每只鬣蜥位于从 1 到 N 的节点上，并且每个节点恰好有一个由数组 p 定义的传出边。 在一个时间步中，每只鬣蜥同时从 i 移动到 p[i]。 唯一的例外是节点 1：鬣蜥 1 从不移动，而是充当其他节点试图到达的固定根。 

每只鬣蜥都会反复遵循这一确定性规则。 一些鬣蜥最终可能会在经过几个步骤后降落在节点 1 上。 其他人可能会陷入从不包含 1 的循环中，在这种情况下，他们永远不会到达领导者并在期望中被忽略。 

我们需要的数量是所有最终能到达节点 1 的鬣蜥第一次到达的平均时间，从时间 0 开始以步长测量。 Iguana 1 本身也包含在内，贡献时间为零。 

输入大小很大：所有测试用例最多有 2·10^5 个节点。 这排除了为每只鬣蜥一步步前进的任何每节点模拟，因为天真地遵循链可能会在长链或周期中退化为二次行为。 

当循环存在时，就会出现一个微妙的问题。 考虑像 2 → 3 → 2 这样的循环，它不连接到 1。反向边中从 1 开始的朴素 BFS 将避免对这些节点进行计数，这是正确的，但我们仍然需要通过长功能链达到 1 的节点的正确距离。 另一个微妙的情况是，图不是树，因此多个节点在合并到循环或节点 1 之前可以共享后缀链。 

边缘情况包括：

 一个简单的链：1 ← 2 ← 3 ← 4。这里的答案是简单的距离 0,1,2,3，平均值是 1.5。 任何错误地将图视为无向图的方法都会导致计数过多。 

无法访问 1 的纯循环，例如 1 → 2 → 3 → 1 加上不相交循环 4 → 5 → 4。节点 4 和 5 必须完全忽略。 

由于 p1 存在但 1 永远不会移动，因此暗示节点 1 处存在自环。 在计算反向结构时，这个细节很重要。 

## 方法

 一个蛮力的想法是独立模拟每只鬣蜥。 对于每个 i，我们重复应用 p[i]，然后应用 p[p[i]]，依此类推，直到达到 1 或检测到重复。 如果我们在步骤 d 达到 1，我们将 d 贡献给总和； 否则我们会忽略它。 这是正确的，因为每个轨迹都是确定性的，并且第一次到达 1 的时间是明确定义的。 

然而，在最坏的情况下，每次行走可能需要 O(N) 步，并且我们对所有节点都执行此操作，从而导致每个测试用例的时间为 O(N^2)。 总体而言，N 高达 2·10^5，这太慢了。 

关键的观察是每个节点都有一个出边，因此该结构是一个函数图。 每个组件都由一个有向循环组成，其中有树木为其提供数据。 只有路径最终到达节点 1 的节点才是重要的，因此我们只关心反转图意义上的吸引盆 1 中的节点。 

一旦我们将注意力限制在可达节点上，问题就简化为计算图中到节点 1 的最短距离，其中每条边的权重均为 1，但边沿 p 向前定向。 在函数图中计算到固定目标的距离的自然方法是反转边并从节点 1 开始运行 BFS。这为我们提供了从每个节点到达 1 所需的最少步数，这正是每只鬣蜥所花费的时间。 

因此，解决方案变为：构建反向邻接列表，从节点 1 运行 BFS，计算距离，并仅对距离有限的节点进行平均。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(N^2) | O(N^2) | O(1) | O(1) | 太慢了|
 | 反向图 BFS | O(N) | O(N) | 已接受 |

 ## 算法演练

 ## 算法演练

1. 构建一个反向邻接表 rev，其中 rev[v] 包含所有节点 u，使得 p[u] = v。这将“我下一步要去哪里”转换为“谁可以一步到达我”，这对于向后搜索至关重要。 
2. 将所有节点的距离数组 dist 初始化为 -1。 这将所有节点标记为最初无法从节点 1 访问。 
3. 设置dist[1] = 0并将节点1推入队列。 节点 1 是 BFS 的源头，因为我们测量到达它需要多少步。 
4. 当队列不为空时，弹出一个节点u。 对于 rev[u] 中的每个节点 v，如果 dist[v] 仍为 -1，则设置 dist[v] = dist[u] + 1 并将 v 推入队列。 这沿着反向边缘向外传播最短到达时间。 
5. BFS 完成后，迭代所有节点。 对于 dist[i] != -1 的每个节点 i，将 dist[i] 添加到运行总和并递增计数器。 
6. 将答案计算为总和/计数。 这仅对实际可以到达节点 1 的节点进行平均。 

工作原理：反转图中的每条边都代表一步有效地向前移动到节点 1。 BFS 以从 1 开始递增的步数探索节点，并且由于所有边的权重相等，因此我们第一次为节点分配距离时保证是到达节点 1 所需的最小步数。未访问的节点正是那些位于与 1 断开的循环或组件中的节点，因此它们被正确排除。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        rev = [[] for _ in range(n + 1)]
        for i in range(n):
            rev[p[i]].append(i + 1)

        dist = [-1] * (n + 1)
        q = deque([1])
        dist[1] = 0

        while q:
            u = q.popleft()
            for v in rev[u]:
                if dist[v] == -1:
                    dist[v] = dist[u] + 1
                    q.append(v)

        total = 0
        cnt = 0
        for i in range(1, n + 1):
            if dist[i] != -1:
                total += dist[i]
                cnt += 1

        out.append(str(total / cnt if cnt else 0.0))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现直接反映了反向 BFS 的思想。 反向邻接表 rev 是使用基于 1 的索引构建的，与问题定义相匹配。 BFS 队列从节点 1 开始，并且 dist[1] 正确设置为零，因为 Iguana 1 已经处于领导者位置。 

一个常见的错误是沿着 p 向前迭代而不是反向迭代。 这将模拟远离 1 而不是朝向 1 的运动，这不会计算到达时间。 另一个微妙的问题是忘记排除无法访问的节点； dist 数组检查确保我们只平均有效的鬣蜥。

 ## 边缘情况

 关键的边缘情况是图主要由不连接到节点 1 的循环组成。在这种情况下，来自节点 1 的 BFS 永远不会到达它们，并且它们一定不会影响平均值。 例如，在 2 → 3 → 2 和 4 → 5 → 4 且 1 被孤立的图中，仅计算节点 1。 反向 BFS 自然地将所有其他节点保留为 dist = -1，因此它们被干净地排除。 

另一个边缘情况是长链中的每个节点最终都指向 1。 例如，1 ← 2 ← 3 ← … ← N。BFS 分配距离 0 到 N−1，平均值变为 (N−1)/2。 该算法无需修改即可处理此问题，因为每个节点按照距离递增的顺序恰好被发现一次。 

第三个微妙的情况是，多个分支在到达循环或节点 1 之前合并。反向 BFS 可以正确处理此问题，因为一旦访问了某个节点，就永远不会重新访问该节点，从而确保仅记录到 1 的最短路径，即使存在多个前向路径也是如此。
