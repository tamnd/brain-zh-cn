 ## 解决方案
 ## 问题理解

 我们得到了一组鸡蛋，每个鸡蛋都可以以三种方式之一使用：可以煎，可以炒，或者可以完全忽略。 每个选择都会对该鸡蛋产生不同的满意度值，并且这些值在鸡蛋之间是独立的。 

煎多少个、炒多少个都有容量限制。 最多$F$鸡蛋最多可以煎一下$S$鸡蛋可以炒。 不需要使用所有可用的插槽，并且每个鸡蛋的决定都是全局的，这意味着将一个鸡蛋分配给煎或炒会减少所有其他鸡蛋的可用性。 

任务是通过将每个鸡蛋最多分配到两种烹饪方法之一或完全跳过它来最大化总体满意度。 

约束条件给出$N \leq 10^4$和$F + S \leq 100$。 这种组合很重要：鸡蛋的数量很大，但“所选物品”的总数却很少。 任何尝试直接探索每个鸡蛋的所有分配的解决方案都会有$3^N$的可能性，这是完全不可行的。 仅当状态空间保持较小时，即使对所有鸡蛋和两种容量进行动态编程也是合理的。 

一个朴素的二维背包$N \times F \times S$在最坏的情况下已经太大了：$10^4 \times 100 \times 100 = 10^8$，这在 Python 中是临界值，当转换非常重要时，速度低于 1 秒。 

当两者都出现时，就会出现微妙的边缘情况$f_i$和$s_i$是负面的。 天真的贪婪方法可能会迫使选择最多$F+S$无论如何，这是不正确的，因为总是允许跳过。 例如，如果所有值都是负数并且$F, S > 0$，正确答案是$0$，通过不选择任何内容来实现。 任何盲目填补能力的做法都会失败。 

另一种边缘情况是当其中之一$F$或者$S$为零。 那么所有鸡蛋都必须仅在一个维度下进行评估，并且混合选择是不可能的。 这减少了选择最多$S$最好炒或最多$F$最好是油炸，但仍然具有每个鸡蛋的独家性。 

关键的困难在于，每个项目都有两种独立的“利润类型”，并且我们必须在两个全局容量限制的情况下，为每个项目最多选择一种类型。 

## 方法

 蛮力方法会尝试将每个鸡蛋分配给三种状态之一：油炸、炒或未使用，同时跟踪到目前为止已使用了多少油炸和炒鸡蛋。 这导致状态空间大致为$3^N$任务，每项任务都需要不断评估。 即使通过容量约束进行修剪也没有多大帮助，因为分支发生在违反约束之前。 这立即呈指数增长。 

更结构化的蛮力视图是对项目和容量的动态规划：让$dp[i][f][s]$代表考虑第一个的最佳答案$i$鸡蛋与$f$油炸和$s$炒用的。 每个鸡蛋都会转变为三种可能性。 这是正确的，但要付出代价$O(NFS)$，在最坏的情况下是$10^4 \cdot 10^4 = 10^8$状态，并且每次转换都是恒定的，所以这在 Python 中太慢了。 

关键的观察结果是容量状态的数量很少：$F + S \leq 100$。 我们可以将决策压缩为每个鸡蛋的单个背包式维度，逐个处理鸡蛋并维护一个 DP 表，而不是直接考虑所有鸡蛋和两个维度上的 DP。$(f, s)$仅有的。 

问题变成了一个经典的小容量的2D背包。 每道菜都提供三种选择：炸的、炒的、或者跳过。 由于每个鸡蛋对任一维度都有独立贡献，因此我们可以在小网格上进行直接 DP。 

我们维护一个 DP 表，其中每个州存储使用加工鸡蛋的某些子集可实现的最大满意度。 每个鸡蛋通过增加油炸数量或炒数量来更新表格。 由于容量很小，我们可以安全地向后迭代状态，以避免多次重复使用同一个蛋。 

这可以减少指数或$NFS$复杂性$N(F+S)^2$，这是可行的，因为$F+S \leq 100$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |

 |---|---|---|

 | 暴力枚举|$O(3^N)$|$O(N)$| 太慢了|

 | 关于物品和容量的 3D DP |$O(NFS)$|$O(NFS)$| 太慢了|

 | 仅针对容量优化 2D DP |$O(N(F+S)^2)$|$O((F+S)^2)$| 已接受 |

 ## 算法演练

 我们将这个问题视为填充一个二维表，该表由我们已经选择了多少个煎蛋和炒鸡蛋来索引。 

1.我们创建一个DP表`dp[f][s]`，初始化为一个非常负的值，除了`dp[0][0] = 0`。 这代表了在精确使用鸡蛋的情况下加工某些鸡蛋前缀后可达到的最佳满意度`f`油炸和`s`炒槽。 我们使用负无穷大来标记无法到达的状态，因此我们永远不会建立在无效的配置上。 
2. 我们逐个迭代每个鸡蛋。 每个鸡蛋都是一个决策点，可以潜在地改善许多状态，因此我们必须仔细更新 DP，不要覆盖我们仍然需要读取的状态。 
3.对于每个egg，我们创建一个新的DP表`ndp`初始化为副本`dp`。 这确保了始终保留跳过鸡蛋，因为跳过相当于保持所有先前的值不变。 
4. 然后我们考虑将当前鸡蛋指定为煎蛋。 对于每个州$(f, s)$在哪里$f < F$，我们尝试过渡到$(f+1, s)$有价值`dp[f][s] + f_i`。 我们更新`ndp[f+1][s]`如果这提高了价值。 This step represents using one fried slot for this egg and accumulating its fried satisfaction.
 5. We similarly consider assigning the egg as scrambled. 对于每个州$(f, s)$在哪里$s < S$，我们过渡到$(f, s+1)$有价值`dp[f][s] + s_i`, 更新`ndp[f][s+1]`因此。 这强制了加扰容量约束。 
6. 处理完所有状态的两个转换后，我们替换`dp`和`ndp`。 这样就完成了一个鸡蛋的加工，同时保持了所有组合的正确性。 
7. 所有鸡蛋处理完毕后，我们扫描所有状态`dp[f][s]`并取最大值。 我们不要求使用所有容量，因为未使用的容量是允许的，并且有时是最佳的。 

### 为什么它有效

 DP 保留了所有可实现的加工鸡蛋配置的完整表示，仅根据使用了多少油炸和炒选项进行索引。 在每一步中，每个状态都对应于先前鸡蛋决策的有效子集。 在处理新鸡蛋时，我们仅以所有合法方式扩展这些有效配置，要么将鸡蛋添加为煎蛋或炒蛋，要么根本不使用它。 因为我们将之前的DP复制到`ndp`，在使用之前不会覆盖任何状态，因此每个转换仅使用来自前一个 Egg 前缀的信息。 这保证了每个可能的有效分配在某个 DP 状态中只被表示一次，并且最终的最大值提取其中最好的分配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, F, S = map(int, input().split())
    
    NEG = -10**30
    dp = [[NEG] * (S + 1) for _ in range(F + 1)]
    dp[0][0] = 0

    for _ in range(N):
        fi, si = map(int, input().split())
        ndp = [row[:] for row in dp]

        for f in range(F + 1):
            for s in range(S + 1):
                if dp[f][s] == NEG:
                    continue
                val = dp[f][s]
                
                if f + 1 <= F:
                    ndp[f + 1][s] = max(ndp[f + 1][s], val + fi)
                if s + 1 <= S:
                    ndp[f][s + 1] = max(ndp[f][s + 1], val + si)

        dp = ndp

    ans = 0
    for f in range(F + 1):
        for s in range(S + 1):
            ans = max(ans, dp[f][s])

    print(ans)

if __name__ == "__main__":
    solve()
```The implementation directly follows the DP definition. 使用复制表`ndp`至关重要，因为它可以防止在一次迭代中多次重复使用同一个鸡蛋。 如果我们就地更新，当前鸡蛋的转换可能会错误地链接并多次计数。 

使用大负数进行初始化可确保无法到达的状态永远不会传播正值。 最终答案适用于所有状态，因为使用的数量少于$F$或者$S$插槽是允许的。

 ## 边缘情况

 一个关键的边缘情况是所有满意度值为负值。 例如：```
3 1 1
-10 -20
-5 -7
-8 -3
```DP 从 0 开始，每次转换都会减少值。 由于总是允许跳过，因此状态`dp[0][0] = 0`仍然可达并主导所有负面状态。 因此最终的最大值为 0，表示不选择鸡蛋。 该算法正确地保留了这一点，因为`ndp`作为以下副本开始`dp`，因此不选择始终是一种选择。 

另一个边缘情况是容量为零时。 如果$F = 0$，油炸过渡是不可能的，因为条件`f + 1 <= F`阻止他们。 该算法干净地退化为一维置乱背包，无需任何特殊外壳。 同样对于$S = 0$。 这表明 DP 公式自然地尊重约束，而不需要单独的分支。 

最后一个微妙的情况是，最佳解决方案使用的数量少于$F + S$鸡蛋总数。 该算法处理这个问题是因为最终答案取所有答案中的最大值$(f, s)$，而不仅仅是满容量边界状态。
