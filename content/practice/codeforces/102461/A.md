 ## 解决方案
 ## 问题理解

 输入是不带空格的有效算术表达式。 其操作数为单个小写字母，表达式中可以包含二元运算符`+`,`-`,`*`,`/`与括号一起。 该任务纯粹是装饰性的：保持表达式原样，但在每个算术运算符之前和之后各放置一个空格。 

例如，`a+b*(c-d)`变成`a + b * (c - d)`。 括号本身没有改变，也没有在它们周围添加空格。 

该表达式最多有 200 个字符，因此即使是二次算法也只能针对官方约束执行少量操作。 不需要解析、运算符优先级处理或表达式求值。 输入已经保证在语法上是正确的，这意味着每个`+`,`-`,`*`， 和`/`我们遇到的是一个需要格式化的运算符。 

线性扫描是自然的解决方案，因为每个字符都需要检查一次。 由于最多 200 个字符，这完全在一秒限制之内，并且使用的内存可以忽略不计。 甚至一个`O(n^2)`构造将通过这些特定的约束，但是当可以直接执行所需的转换时，没有理由使用它`O(n)`。 

第一个边缘情况是不包含运算符的表达式。 用于输入`a`，正确的输出是`a`。 总是在表达式末尾插入空格的粗心实现会产生诸如`a`，这会更改不应该修改的字符。 

第二个边缘情况是括号旁边的运算符。 用于输入`(a)/(b)`，正确的输出是`(a) / (b)`。 空间属于周围`/`，不在周围`(`或者`)`。 将每个非字母字符视为需要周围空格的实现会错误地修改括号。 

第三种边缘情况是深度嵌套的表达式。 用于输入`((a))-b+(c*(d))`，正确的输出是`((a)) - b + (c * (d))`。 括号可以紧接在运算符之前或之后出现，因此实现必须根据字符本身而不是其在表达式中的位置来决定。 

第四种边缘情况是由单字母变量分隔的多个运算符。 用于输入`a+b+c+d`，正确的输出是`a + b + c + d`。 仅处理第一个运算符的解决方案，或者在向前移动索引时将空格插入原始字符串而不考虑插入的字符的解决方案可以跳过后面的运算符。 

## 方法

 一个简单的暴力解决方案可以重复搜索运算符并构造一个周围有空格的新字符串。 如果当前表达式有长度`m`，通过重建整个字符串插入空格即可复制`O(m)`人物。 如果有`k`运算符，每次插入后长度都会增加，因此总工作量为`O(nk)`，即`O(n^2)`在最坏的情况下。 对于此处最大实际长度的表达式（大约 200 个字符），这仅是数万个字符操作的数量级，因此对于给定的约束，这种方法实际上足够快。 

暴力方法之所以有效，是因为每个操作员都可以独立处理。 它的弱点不在于正确性，而在于不必要的重复工作。 处理完一个运算符后，它可能会复制许多已处理过的字符以到达下一个运算符。 

关键的观察结果是所需的输出仅取决于当前的输入字符。 如果该角色是以下之一`+`,`-`,`*`， 或者`/`，我们附加一个空格，然后是运算符，然后是另一个空格。 所有其他字符均按原样复制。 不同运算符之间没有交互，并且插入空格不会改变任何后续输入字符的解释方式。 

这让我们可以从左到右处理原始表达式一次。 我们永远不会修改输入字符串，也永远不需要因为插入空格而调整索引。 结果是单独构建的，因此每个输入字符都会在恒定时间内处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n^2)`|`O(n)`| 接受为`n <= 200`|
 | 最佳 |`O(n)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 将完整的表达式作为字符串读取。 由于该语句保证输入不包含空格，因此读取一行就足够了。 
2. 创建一个空列表来存储最终表达式的各个部分。 列表很方便，因为向其追加内容的时间是恒定的，并且在最后加入一次可以避免重复创建新的不可变的 Python 字符串。 
3. 从第一个字符到最后一个字符扫描输入。 对于每个字符，检查它是否是四个算术运算符之一。 
4. 如果字符是运算符，则将三部分附加到结果中：一个空格、运算符本身和另一个空格。 这直接实现了所需的格式化规则。 
5. 如果该字符不是运算符，则将其原样追加。 特别是，括号和变量必须保持原样。 
6. 将所有结果片段连接成一个字符串并打印它。 由于输入不包含现有空格，因此这会在每个运算符的每一侧创建一个空格，而不会在其他地方创建空格。 

### 为什么它有效

 处理输入的任何前缀后，结果列表将准确包含该前缀的格式正确的版本。 变量或括号被原封不动地复制，而每个算术运算符都被恰好由一个空格包围的运算符替换。 处理下一个字符会保留此属性，因此通过归纳，扫描完成时整个表达式的格式正确。 因为每个决定仅基于当前输入字符，所以任何运算符都不能被跳过或处理两次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def format_expression(s):
    operators = {"+", "-", "*", "/"}
    result = []

    for ch in s:
        if ch in operators:
            result.append(" ")
            result.append(ch)
            result.append(" ")
        else:
            result.append(ch)

    return "".join(result)

def main():
    s = input().strip()
    print(format_expression(s))

if __name__ == "__main__":
    main()
```这`operators`set 恰好包含需要格式化的四个字符。 对于每个输入字符，检查该集合中的成员资格需要恒定的时间。 

这`result`列表代表正在构建的输出。 当找到运算符时，代码会附加三个单独的字符串，而不是修改输入字符串。 这是 Python 中的一个有用的实现细节，因为字符串是不可变的，因此重复插入字符串可能需要每次复制它的很大一部分。 

循环处理原始输入，而不是不断增长的输出。 这种区别消除了该问题中最常见的索引错误。 如果我们在正在扫描的字符串中插入空格，则当前位置将在每个运算符之后移动。 在这里，输入永远不会改变，因此循环索引始终引用正确的原始字符。 

决赛`"".join(result)`执行输出字符串的一种构造。 没有整数运算，因此整数溢出是无关紧要的，并且输入长度非常小，标准 Python I/O 绰绰有余。

 ## 边缘情况

 对于表达式`a`，算法只看到一个字符。 自从`a`不在运算符集中，则直接复制到结果中。 最终输出是`a`，因此当不需要格式化时，该解决方案不会引入不需要的空格。 

为了`(a)/(b)`，前三个字符是`(`,`a`， 和`)`，所有这些都被原封不动地复制。 什么时候`/`达到时，算法附加`/`作为一个逻辑运算。 其余字符原封不动地复制，产生`(a) / (b)`。 这处理了运算符和括号之间的边界，而不将括号本身视为运算符。 

为了`((a))-b+(c*(d))`，每个左括号和右括号都按其显示的样子进行复制。 什么时候`-`,`+`， 和`*`遇到时，每一个都在两侧各留出一个空间。 结果是`((a)) - b + (c * (d))`。 嵌套结构对算法没有影响，因为任务不需要解析表达式。 

为了`a+a+a+a+a`， 每个`+`是独立处理的。 第一个运算符之后的结果包含`a + `，在第二个之后它包含`a + a + `， 等等。 最终输出是`a + a + a + a + a`。 这证实了扫描会继续扫描每个原始字符，并且不会因为将空格添加到单独的结果中而丢失其位置。 

对于由 100 组成的最大长度表达式`a`由 99 连接的变量`+`运算符，扫描对 199 个输入字符中的每一个执行一个恒定时间决策。 99 个运算符中的每一个都恰好产生两个空格，因此输出有 397 个字符。 该算法在输入大小上保持线性，并轻松处理最大的有效表达式。
