 ## 解决方案
 ## 问题理解

 我们从 10,000 名订阅者开始。 有两种视频。 常规视频会增加订阅者数量`a_i`并且不提供直接收入。 商业视频有参数`c_i`和`b_i`: 发布后就赚了`c_i`当前存在的每个订阅者的美分，然后订阅者数量减少`b_i`。 

对于每个请求的号码`d`，我们必须准确选择`d`从准备好的视频中挑选视频，并以尽可能最佳的顺序排列这些选定的视频。 答案是最大的广告总收入。 原来的约束条件有`n,m <= 100`,`a_i,b_i,c_i <= 100`，时间限制为 1 秒，内存为 512 MB。 

的小值`n`和`m`排除枚举任意子集或排列的算法。 有了 200 个可用视频，即使枚举所有可能的排序也已经需要以下顺序：`200!`，这远远超出了任何可行的范围。 有用的数字界限是所有商业的总和`c_i`值最多为 10,000。 这给了我们一个易于管理的背包般的尺寸。 

在一些边缘情况下，简单的实现可能会默默地出错。 如果`d = 0`，答案恰好为零，因为不能发布商业视频。 例如，```

## 方法

 直接的方法是枚举每个可能的视频集以及该集的每个顺序。 对于固定的`d`, 有

 [
 P(n+m,d)=\frac{(n+m)!}{(n+m-d)!}
 ]

 有序的选择。 如果所有可能的值`d`查询到的调度总数为

 [
 \sum_{d=0}^{n+m} P(n+m,d)。 
]

和`n+m=200`，这已经包含术语`200!`， 大约`7.9 * 10^374`。 蛮力是正确的，因为每一个可能的选择和每一个可能的顺序都被考虑了，但它几乎立即变得无用。 

第一个有用的观察是，常规视频应始终出现在商业视频之前。 假设一个普通视频的订阅者数量增加了`a`，以及带有系数的商业视频`c`目前发布于`s`订户。 先发布广告视频即可获得收益`c*s`。 先发布常规视频即可获得收益`c*(s+a)`，它严格来说更大。 因此，为答案选择的每个常规视频都可以移到前面，而不会损害利润。 

第二个观察结果是，一旦商业视频集固定，它们的相对顺序就会通过简单的成对交换论证来强制。 考虑商业视频`x`和`y`，并假设有`s`在他们之前的订户。 如果`x`之前被释放`y`，他们的总收入是

 [
 c_xs+c_y(s-b_x)。 
]

如果`y`之前被释放`x`，它是

 [
 c_ys+c_x(s-b_y)。 
]

 第一个订单至少同样好

 [
 c_xb_y \ge c_yb_x,
 ]

 这相当于

 [
 \frac{c_x}{b_x}\ge\frac{c_y}{b_y}。 
]

 因此商业视频必须按降序出现`c/b`。 

现在修复该顺序并假设我们选择一些商业视频。 如果我们以相反的顺序处理它们，即增加`c/b`，添加带有参数的商业视频`(c,b)`先前处理的广告导致处罚后

 [
 b \cdot C,
 ]

 哪里`C`是总和`c`先前处理的广告的值。 这给出了背包式动态程序。 

让`dp[k][s]`是精确选择后的最大负惩罚`k`商业视频总数`c`是`s`。 下一个广告视频什么时候有参数`(c,b)`，跳过它不会改变任何事情。 接受它会将状态更改为

 \max(dp[k+1][s+c], dp[k][s]-b\cdot s)。 
]

 实际收入就很容易重建。 如果所选的商业视频总共有`c`等于`s`，以及精选的常规视频贡献`A`额外的订阅者，每个商业视频看到的初始订阅者数量是`10000+A`。 因此他们的基本收入是

 [
 秒(10000+A),
 ]

 而DP值正好减去之前商业视频带来的损失。 

对于固定数量`l`常规视频中，我们应该选择`l`最大的`a_i`价值观。 每个选定的常规视频都放置在每个商业视频之前，因此其全部贡献乘以总贡献`c`选定的商业视频。 没有理由选择较小的`a_i`。 

还有一项对 Python 有用的优化。 对于固定数量`k`每个 DP 州的商业视频`(s, dp[k][s])`代表一条线

 [
 f(x)=s x+dp[k][s],
 ]

 哪里`x=10000+A`是所有广告之前的订阅者数量。 我们需要这些线的最大值来满足几个不断增加的值`x`，每个可能数量的常规视频一个。 由于斜坡`s`正在增加，上包络可以用单调凸包构造并在线性时间内查询。 

蛮力方法之所以有效，是因为它明确地表示了每个可能的调度，但由于存在阶乘多个调度，所以会失败。 观察到常规视频和商业视频的顺序可以规范化，其次是固定的`c/b`广告排序，将问题简化为总商业系数上的有界背包 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(sum P(n+m,d))`|`O(n+m)`| 太慢了|
 | 最佳 |`O(m²C + nm + m log m)`， 在哪里`C=sum c_i <= 10000`|`O(mC + n)`| 已接受 |

 该实现还将每次 DP 扫描限制为每个可达到的最小和最大总和。`k`，这比扫描所有要小得多`C`在许多输入中的位置。 

## 算法演练

 1.按降序对常规视频增加进行排序并构建前缀和。 如果我们准确地使用`l`常规视频，最好的总增量是第一个的前缀和`l`价值观。 这是有效的，因为每个常规视频都会在每个商业视频之前发布，因此每个额外的订阅者都会平等地帮助每个选定的广告。 
2. 将每个商业视频存储为`(c,b)`并通过增加对它们进行排序`c/b`。 实际最优释放顺序是递减的`c/b`，但是以相反的顺序处理广告可以使DP转换变得方便。 等比率可以任意排序，因为交换等比率广告不会改变收入。 
3. 定义`dp[k][s]`作为选择的负交互惩罚的最大值`k`商业视频总系数`s`在迄今为止处理的广告中。 最初仅`dp[0][0] = 0`是可达的。 
4、对广告视频进行一一处理。 对于视频`(c,b)`, 迭代`k`向下，因此同一视频不能选择两次。 对于每一个可达到的金额`s`，跳过视频会使状态保持不变。 选择它会创建状态`(k+1, s+c)`有价值`dp[k][s] - b*s`。 

期限`b*s`有直接的意义。 所有之前处理过的广告都贡献了自己的力量`c`值与总系数的比值`s`，在他们之后发布当前广告就意味着输了`b`每个系数单元的订阅者。 
5. 对于每个数字`k`选定的广告，解释每个有限的 DP 状态`(s,dp[k][s])`作为一条线`s*x + dp[k][s]`。 这里`x`是所有选定的常规视频之后、广告序列之前的订阅者数量。 
6. 建造这些线路的上船体。 斜率已经在增加，因为斜率恰好是总斜率`c`价值`s`。 当中间线与上一行的交点不早于上一行与下一行的交点时，删除中间线。 对于任何查询来说，这样的行永远不可能是最佳的`x`。 
7. 查询船体中每个可能的数字`l`常规视频。 查询值为`10000 + prefix[l]`。 如果船体给`profit_ads`，那么发布的视频总数为`d=l+k`，所以更新`answer[d]`与这个值。 
8. 读取请求的值`d`并打印相应的预先计算的答案。 既然一切皆有可能`d`在读取查询之前处理值，每个查询都会在恒定时间内得到答复。 

### 为什么它有效

 对于每个可行的时间表，将所有选定的常规视频移到前面并不能减少任何商业视频的订阅者数量，因此最佳时间表首先是所有常规视频。 在选定的商业视频中，两两交换计算证明，减少`c/b`是唯一最优的相对排序，直至并列。 DP 的处理过程与此顺序正好相反，并且其转换减去`b`乘以总数`c`已处理的广告数量，这正是因为这些广告发布较早而损失的收入。 因此，每个商业子集都具有由一个 DP 状态表示的最优惩罚。 最后，选择最大的常规视频增量对于每个固定数量的常规视频来说是最佳的，并且外壳会针对每个最终订阅者数量评估最佳商业子集。 因此，最终最大化所考虑的每个组合对于其发布的视频数量都是最佳的，并且考虑了每个可能的数量。 

## Python 解决方案```python
import sys
from functools import cmp_to_key

input = sys.stdin.readline

NEG = -10**30
INF = 10**30
INITIAL = 10000

def solve():
    n = int(input())
    good = [int(input()) for _ in range(n)]
    good.sort(reverse=True)

    pref = [0]
    for x in good:
        pref.append(pref[-1] + x)

    m = int(input())
    ads = []
    total_c = 0

    for _ in range(m):
        c, b = map(int, input().split())
        ads.append((c, b))
        total_c += c

    # DP is processed in increasing c / b order.
    # The actual release order is the reverse.
    def cmp(x, y):
        left = x[0] * y[1]
        right = y[0] * x[1]
        if left < right:
            return -1
        if left > right:
            return 1
        return 0

    ads.sort(key=cmp_to_key(cmp))

    # dp[k][s] = maximum negative interaction penalty
    # for k ads with total coefficient s.
    dp = [[NEG] * (total_c + 1) for _ in range(m + 1)]
    dp[0][0] = 0

    # Exact lower/upper bounds on possible total c for k selected
    # advertisements among the already processed advertisements.
    min_sum = [INF] * (m + 1)
    max_sum = [NEG] * (m + 1)
    min_sum[0] = 0
    max_sum[0] = 0

    processed = 0

    for c, b in ads:
        # Descending k makes the update 0/1: the current advertisement
        # cannot be used again during this iteration.
        for k in range(processed, -1, -1):
            lo = min_sum[k]
            hi = max_sum[k]

            if lo == INF:
                continue

            row = dp[k]
            nxt = dp[k + 1]

            for s in range(lo, hi + 1):
                val = row[s]
                if val == NEG:
                    continue

                ns = s + c
                nv = val - b * s

                if nv > nxt[ns]:
                    nxt[ns] = nv

        # Update reachable sum bounds after using this advertisement.
        for k in range(processed, -1, -1):
            if min_sum[k] != INF:
                v = min_sum[k] + c
                if v < min_sum[k + 1]:
                    min_sum[k + 1] = v

            if max_sum[k] != NEG:
                v = max_sum[k] + c
                if v > max_sum[k + 1]:
                    max_sum[k + 1] = v

        processed += 1

    # Build upper hull and query it for every possible subscriber count.
    #
    # A line is represented by y = slope * x + intercept.
    # Slopes are increasing because slope = total commercial c.
    def build_hull(k):
        hull_m = []
        hull_b = []

        lo = min_sum[k]
        hi = max_sum[k]

        if lo == INF:
            return hull_m, hull_b

        row = dp[k]

        for s in range(lo, hi + 1):
            intercept = row[s]
            if intercept == NEG:
                continue

            while len(hull_m) >= 2:
                m1 = hull_m[-2]
                b1 = hull_b[-2]
                m2 = hull_m[-1]
                b2 = hull_b[-1]

                # Remove the middle line if:
                # (b1-b2)/(m2-m1) >= (b2-intercept)/(s-m2)
                if (b1 - b2) * (s - m2) >= \
                   (b2 - intercept) * (m2 - m1):
                    hull_m.pop()
                    hull_b.pop()
                else:
                    break

            hull_m.append(s)
            hull_b.append(intercept)

        return hull_m, hull_b

    answer = [NEG] * (n + m + 1)

    for k in range(m + 1):
        hull_m, hull_b = build_hull(k)

        if not hull_m:
            continue

        pointer = 0

        for l in range(n + 1):
            x = INITIAL + pref[l]

            while pointer + 1 < len(hull_m):
                cur = hull_m[pointer] * x + hull_b[pointer]
                nxt = hull_m[pointer + 1] * x + hull_b[pointer + 1]

                if nxt >= cur:
                    pointer += 1
                else:
                    break

            profit = hull_m[pointer] * x + hull_b[pointer]
            d = k + l

            if profit > answer[d]:
                answer[d] = profit

    q = int(input())
    out = []

    for _ in range(q):
        d = int(input())
        out.append(str(answer[d]))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```输入部分首先对常规增量进行排序并构建它们的前缀和。`pref[l]`是可从以下位置获得的最大总订户增量`l`常规视频。 

商业视频是通过交叉乘法而不是浮点除法来排序的。 比较器放置较小`c/b`首先是因为 DP 向后处理最优商业订单。 使用`c1 * b2`和`c2 * b1`避免了所有可能的浮点比较问题。 

DP 对每个可能数量的选定广告使用一个数组。 迭代`k`向下是标准的 0/1 背包方向。 如果我们向上迭代，当前的广告可以在同一次迭代中重复使用。 

DP总和是总和`c`，不是总数`b`。 这是核心实施细节。 当广告减少时`b`放置在广告之后，其系数和为`s`，其收入正好减少了`b*s`。 这就是为什么过渡减去`b * s`。 

这`min_sum`和`max_sum`数组只是一种实现优化。 他们记录了最小和最大可能的总数`c`对于每个`k`，因此内循环不会扫描 DP 行中不可能的位置。 这`NEG`哨兵的选择远远低于每个可行的答案，而Python整数具有任意精度，因此溢出不是问题。 

最后的外壳步骤将每个 DP 状态变成一条线。 其斜率就是总商业系数`s`，其截距是 DP 存储的交互惩罚。 由于订户数量`x`仅随着选择更多常规视频而增加，船体查询可以单调前进。

## 复杂度分析

 让

 [
 C=\sum_{i=1}^{m} c_i。 
]

 因为每一个`c_i <= 100`和`m <= 100`，我们有`C <= 10000`。 

| 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(m²C + nm + m log m)`| DP 有`m`层层广告和`m`可能选择的计数总计为`C`; 船体构造扫描每个 DP 行一次 |
 | 空间|`O(mC + n + m)`| 民主党有`(m+1)(C+1)`状态，前缀和和广告数据分开存储 |

 DP 的正式最坏情况大约是`100 * 100 * 10000 = 10^8`基本的国家立场。 该实施避免了扫描无法到达的金额，这在商业应用时尤其有效`c_i`值相等或具有较大的共同结构。 船体去除了额外的`O(nmC)`直接实现使用的最终扫描。 DP 的内存使用量约为一百万个整数引用，完全在 512 MB 限制之内。

 ## 边缘情况

 零视频案件由国家处理`dp[0][0] = 0`。 最终的船体为`k=0`包含单行`y=0`，所以选择`l=0`普通视频的答案为零。 为了```
0
0
1
0
```程序打印`0`。 

当没有商业视频的时候，`m=0`，DP仅包含`dp[0][0]`。 无论选择了多少个常规视频，每个船体查询的计算结果都为零。 因此对于```
2
5
7
0
3
0
1
2
```三个答案是`0`,`0`， 和`0`。 

什么时候`d`超过了可用商业视频的数量，最终的最大化会自动考虑以下状态`k=m`和`l=d-m`。 为了```
2
5
6
1
10 1
1
2
```通过两个视频获得正利润的唯一方法是选择商业视频和一个常规视频。 最大的常规增量是 6，所以答案是`10 * 10006 = 100060`。 

排序边缘情况由比率排序处理。 为了```
0
2
10 20
20 10
1
2
```DP 顺序为`(10,20)`其次是`(20,10)`， 因为`10/20 < 20/10`。 对应的实际释放顺序是相反的。 总系数为 30，第二次 DP 转换会受到惩罚`10 * 10 = 100`。 由此产生的利润是`30 * 10000 - 100 = 299900`。 

最后，关于订阅者计数的保证意味着每个考虑的序列在非负订阅者计数的情况下仍然有效。 该算法永远不需要基于订阅者的消极性来拒绝 DP 状态，因为即使在单独发布所有商业视频的最坏情况下，该问题也保证了可行性。 

外壳优化对于理解核心思想来说并不是必需的，但它使 Python 实现比直接翻译的最终版本更加实用`O(nmC)`扫描。
