 ## 解决方案
 ## 问题理解

 通过选择分割点来构建有效的输出`k`在一个字符串中。 选择后`k`，可见字符串成为前缀`s[1..k]`其次是它的相反。 因此，每个候选答案都是一个“从前缀构建”的回文。 

任务是隐式尝试每一种可能的分割，并选择字典顺序最小的结果回文。 对于多个测试用例和总字符串长度高达 100,000 的情况，任何显式构造所有候选或比较每个候选的完整字符串的解决方案`k`已经太慢了。 一种构建一切的天真的方法`n`回文并比较它们的成本`O(n^2)`每次测试都需要时间和记忆力，这立即是不可行的。 

真正的限制是字典比较对第一个不匹配很敏感，所以我们只关心前缀多久停止改进答案。 这暗示我们根本不应该比较完整构造的字符串。 

当最佳答案使用相对较小的值时，就会出现常见的失败情况`k`，但是贪心算法假设单调性并提前停止。 例如，在像这样的字符串中`bbaaa`，选择`k = 1`给出`bb`， 尽管`k = 3`给出`bbbaaabbb`。 天真的贪婪试图延伸`k`虽然改进前缀可能会错误地提交到更大的`k`因为后来的对称性“在局部看起来更好”，尽管按字典顺序它在中点之后立即变得更糟。 

另一个陷阱是假设一旦前缀开始按字典顺序增加，它将继续增加`k`。 这是错误的，因为后缀部分镜像了前缀，并且改变`k`同时更改前缀和镜像尾部。 

## 方法

 蛮力的想法很简单。 对于每一个`k`从`1`到`n`,构造回文`s[1..k] + reverse(s[1..k])`并与当前最好的进行比较。 每项建设费用`O(k)`，所以完整的解决方案是`O(n^2)`每个测试用例。 总共有`n`最多 100,000，这至少变成`10^10`操作，远远超出了限制。 

关键的观察结果是所构建的弦的结构是刚性的。 第一个`k`个字符恰好是原始字符串的前缀，因此在所有候选中，答案第一个不同的地方也必须位于该前缀区域内。 镜像后缀并没有带来新的自由； 它只重复前缀已经固定的信息。 

因此，两个候选之间的比较简化为在特定规则下比较原始字符串的前缀：扩展`k`只有在比较通过镜像“环回”之前改进字典顺序上较小的前缀段时才重要。 这将问题转化为在单调扫描下维护最佳前缀。 

我们没有明确地构建回文，而是通过模拟候选答案的词典增长并跟踪最佳有效分割点来比较候选答案。 由于后半部分是由前半部分决定的，因此我们只需要推断镜像时前缀的行为方式，即可增量跟踪。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(n^2) | O(n^2) | 太慢了 |
 | 贪婪前缀扫描 | 每次测试 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个字符串。 

1. 首先假设`k = 1`是最优的。 最初的候选人只是`s[0] + s[0]`，所以我们只跟踪第一个字符作为基线。 
2、扫一扫`k`从左到右。 在每个位置`i`，我们考虑扩展前缀是否可以改善生成的回文。 由于后半部分反映了前缀，因此扩展`k`以相反的顺序在前缀末尾和后缀开头添加新字符。 
3. 通过比较如果我们选择当前的结果会发生什么，我们按字典顺序维护最佳答案`k`与之前的最佳成绩相比`k`。 我们不构建完整的字符串，而是仅比较直到有效镜像结构中出现第一个不匹配为止。 
4. 比较简化为在向前读取时检查新前缀在字典顺序上是否小于先前的最佳前缀。 如果是，我们会更新候选答案。 
5. 扫描所有位置后，我们使用最佳的构建最终答案`k`： 输出`s[:k] + s[:k][::-1]`。 

重要的隐藏步骤是我们在比较过程中从不显式模拟完整的回文。 我们只依赖前缀比较，因为镜像后缀没有引入独立的排序信息。 

### 为什么它有效

 每个候选输出完全由其前缀决定。 当比较两个不同的候选人时`k`，它们不同的第一个位置必须出现在第一个`min(k1, k2)`字符，因为两个字符串都以其原始前缀开头。 在那之后，在镜像的一半影响任何事情之前，字典顺序就已经决定了。 这使得问题相当于在字典顺序约束下选择最佳前缀，因此线性扫描就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        # best k starts at 1
        best_k = 1

        # we track the best prefix string so far
        best = s[0]

        cur = ""
        for i in range(n):
            cur += s[i]

            # compare current prefix with best prefix
            # lexicographically smaller prefix yields smaller full palindrome
            if cur < best:
                best = cur
                best_k = i + 1

        ans = best + best[::-1]
        print(ans)

if __name__ == "__main__":
    solve()
```实现直接遵循只有前缀才重要的观察结果。 变量`best`存储迄今为止看到的最佳前缀，并且`best_k`追踪其长度。 每个步骤都会扩展当前前缀并执行字典顺序比较。 使用所选前缀一次构建最终答案。 

微妙的一点是，虽然循环内的字符串连接看起来可能会变成二次方，但所有测试用例的总长度是有界的，因此在实践约束中总体上仍然是线性的。 更优化的实现将使用切片或滚动比较，但逻辑保持不变。

 ## 边缘情况

 对于像这样的字符串`aaaaa`，每个前缀都是相同的，所以任何`k`产生相同的回文。 该算法保留第一次出现的情况，因为后面的前缀都不会严格小于。 这确保了确定性的输出。 

对于像这样的字符串`zab`, 第一个字符`z`立即在词典中占据主导地位。 即使后来的前缀包含较小的字符，例如`a`，它们出现在`z`在前缀比较中，所以它们永远不会击败最初的选择。 这证实了该算法正确地优先考虑了最早的词典改进，而不是后来的局部最小值。
