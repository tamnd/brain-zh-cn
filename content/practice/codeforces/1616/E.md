 ## 解决方案
 ## 问题理解

 给定两个长度相等的字符串，并且允许我们仅通过交换相邻字符来修改第一个字符串。 每次交换都会花费一次操作。 目标是使用最少的交换次数使第一个字符串的字典顺序小于第二个字符串的结果版本，或者确定它根本无法完成。 

关键的困难在于我们并没有尝试对字符串进行完全排序或将其转换为特定目标。 相反，我们只关心转换后的字符串变得严格小于固定字符串的时刻`t`根据字典顺序比较，我们希望尽可能便宜地达到这种状态。 

长度的约束总和高达 2 × 10^5 意味着每个测试用例的任何解决方案都必须接近线性或线性算数。 如果简单地重新计算成本，任何显式模拟交换或尝试第一个不匹配的所有位置的方法都会太慢。 这些操作是相邻的交换，因此每个移动成本实际上是一个反转距离，这表明我们跟踪角色移动的距离而不是模拟交换的结构。 

出现微妙的边缘情况时`s`按字典顺序已经小于`t`。 在这种情况下，答案为零，但前提是`s < t`在开始时，如果在重新排列后变得更小则不会。 另一个棘手的情况是当`s`无论我们如何排列它都不能变小，例如当两个字符串包含相同的多重集并且`s`已经是字典上最大的排列`t`。 贪婪地修复第一个不匹配的天真贪婪方法可能会失败，因为后来的交换可能会使早期的改进失效。 

贪婪失败的例子：```
s = "bca"
t = "bac"
```贪婪地修复第一个字符可能会导致不必要的交换，而最佳策略取决于我们将较小的字符向前推进多远。 

中心观察是字典顺序比较仅取决于字符串不同的第一个位置，因此我们应该尝试创建最早的位置`s[i] < t[i]`，同时确保所有先前的位置都是平等的。 

## 方法

 一个蛮力的想法是在一定限度内模拟所有可能的相邻交换序列，并检查我们是否可以使`s`小于`t`。 每次交换都会生成一个新状态，因此这本质上是排列的最短路径。 分支因子较大，状态空间为`n!`，所以即使快速修剪也变得不可行。 即使是状态上的 BFS 也是不可能的`n ≤ 10`。 

下一个天真的改进是固定第一个位置`i`我们想要的地方`s[i] < t[i]`，然后尝试带一个小于`t[i]`就位`i`使用相邻的交换。 对于每个候选字符，我们将其成本计算为将其向前推进所需的反转次数。 然而，如果我们从头开始重新计算每个职位的这些成本，我们会得到`O(n^2)`每个测试用例，这太慢了。 

关键的见解是从左到右处理位置并保持每个角色当前所在的位置。 我们维护一个动态结构，支持查找最近出现的字符并在“使用”它时将其删除，而不是重新计算距离。 芬威克树或位置上的 BIT 允许我们计算两个索引之间有多少个活动字符，这直接给出了交换成本。 

策略变为：对于每个位置`i`，我们询问是否可以放置一个角色`c < t[i]`在位置`i`以最小的成本，同时保持所有早期位置不变。 我们使用剩余仓位的订单统计数据来计算成本。 当我们从原始位置“删除”一个字符时，我们会采用所有有效选择中的最小值并更新结构。 

这将问题变成了对对数成本查询的位置的贪婪扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力状态搜索 | O(n!) | O(n!) | 太慢了 |
 | 天真的位置固定| O(n²) | O(n) | 太慢了 |
 | 基于BIT的贪心| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1.首先检查是否`s`按字典顺序已经小于`t`。 如果是，我们返回`0`。 这是安全的，因为没有任何操作可以将成本进一步降低到零，并且我们可以立即停止。 
2. 我们维护一个结构来跟踪哪些位置`s`仍然“未使用”。 最初，所有位置均处于活动状态。 我们还为每个字符维护一个其位置队列，以便我们可以有效地检索出现的情况。 
3.我们迭代索引`i`from left to right, treating it as the first position where a strict inequality might be created.
 4.就位`i`，我们考虑是否可以放置任何严格小于`t[i]`。 对于每个角色`c`从`'a'`到`t[i]-1`，我们检查是否存在未使用的出现`c`。 
5. 如果该位置存在这样的情况`j`，我们计算将其移动到位置的成本`i`。 成本是当前活跃角色的数量`j`和`i`，它代表需要多少掉期才能剩下泡沫。 这是使用 Fenwick 树计算的。 
6. 我们在所有有效的成本中取最小的成本`c`并更新全局候选答案。 
7. 独立而言，我们还必须保持先前职位的平等。 如果`s[i]`仍然可用，我们将其“匹配”到位置`i`将其从活动集中删除并继续。 
8. 答案是在所有位置中找到的最低成本，前提是至少有一个有效位置是可以实现的。 如果没有位置允许`s < t`，我们返回`-1`。 

### 为什么它有效

 该算法依赖于处理索引之前的不变量`i`, 所有位置`< i`已经固定以匹配`t`以最小的成本尽可能接近。 任何有效的解决方案都必须不同于`t`在引入不平等的第一个位置，因此枚举每个索引处的候选点涵盖了所有最佳断点。 芬威克树确保实现每个候选的成本精确地计算为在不干扰先前固定位置的情况下使角色前进所需的交换次数。 由于每个字符仅被删除一次，因此不会发生重复计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        i += 1
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        if i < 0:
            return 0
        i += 1
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        s = list(input().strip())
        t = list(input().strip())

        if s < t:
            print(0)
            continue

        pos = [[] for _ in range(26)]
        for i, ch in enumerate(s):
            pos[ord(ch) - 97].append(i)

        used = [False] * n
        bit = BIT(n)

        for i in range(n):
            bit.add(i, 1)

        ans = float('inf')

        for i in range(n):
            ci = ord(t[i]) - 97

            for c in range(ci):
                if pos[c]:
                    j = pos[c][-1]
                    if not used[j]:
                        cost = bit.range_sum(j, i) - 1
                        ans = min(ans, cost)

            if pos[ord(s[i]) - 97]:
                j = pos[ord(s[i]) - 97].pop()
                used[j] = True
                bit.add(j, -1)

        print(ans if ans != float('inf') else -1)

if __name__ == "__main__":
    solve()
```芬威克树跟踪任何前缀中仍处于活动状态的字符数量。 删除一个字符相当于将其标记为已使用并更新 BIT。 表达式`bit.range_sum(j, i) - 1`准确计算将角色带到该位置所需的交换次数`j`就位`i`。 

一个微妙的点是我们总是从列表中取出最后一次出现的字符。 这是有效的，因为我们有效地消耗了反向发生的事件，这与最大限度地减少早期位置的干扰是一致的。 

早期检查`if s < t`避免在已经有效的情况下进行不必要的计算。

 ## 边缘情况

 一个重要的边缘情况是当没有字符小于`t[i]`存在于任何地方`s`在某个位置`i`。 在这种情况下，算法会正确继续而不更新答案，因为无法在该索引上创建有效的词典改进。 

另一个边缘情况是当`s`已经小于`t`。 该算法在构建任何结构之前立即返回零，从而避免不必要的计算并确保琐碎输入的正确性。 

最后一种情况是最佳移动涉及最右边的角色。 BIT 可确保正确计算所有中间字符，因此即使是长途交换也能准确计费。
