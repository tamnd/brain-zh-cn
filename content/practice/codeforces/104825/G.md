 ## 解决方案
 ## 问题理解

 我们有一个网格，其中每个单元格要么是空的，要么包含一个敌方单位。 空单元格和网格外的区域已经由我们控制。 网格开始时所有敌方细胞都还活着，目标是消灭所有敌方细胞。 

在任何时刻，我们都只能攻击与至少一个友方单元相邻的敌方单元，其中友方来自网格中的零单元或外部边界。 当我们攻击这样的单元格时，我们支付的成本取决于当时剩余敌人配置的结构：成本是单元格本身的一个单位加上其四个方向的邻居中的每个单位的额外单位，这些邻居在移除时仍然包含敌人。 支付费用后，该细胞变得友好。 

任务是选择移除所有敌方细胞的顺序，以使总成本最小化。 

这些约束允许网格大小最大为 1000 x 1000，即最多 100 万个单元。 任何试图在每次删除时动态重新计算邻居计数的同时逐步模拟该过程的解决方案都会太慢。 即使每次去除方法的线性时间也会导致粗略的$10^{12}$在最坏的情况下进行操作，这是不可行的。 

一个微妙的一点是，成本取决于网格的当前状态，而不是初始状态。 这让人很容易认为需要贪婪排序或模拟。 另一个陷阱是假设删除 BFS 或周长顺序中的单元会以复杂的方式改变边缘的贡献，而实际上成本具有隐藏的可加性。 

边缘情况主要与结构有关：

 如果所有敌方单元格都被隔离，例如单个单元格的棋盘状图案，则每次移除的成本恰好为 1，因为没有单元格具有敌方邻居。 答案等于 1 的数量。 

如果所有单元格都是敌人$n \times m$在网格中，天真的直觉可能表明成本在很大程度上取决于移除顺序，但实际上该结构迫使每个相邻对只贡献一次，无论顺序如何。 

## 方法

 暴力方法将明确模拟所有有效的移除命令。 在每一步中，我们都会识别当前所有可移除的敌方单元，尝试移除每个单元，并递归地或通过回溯来跟踪由此产生的成本。 这正确地对问题进行了建模，因为它遵循精确的规则定义，但分支因子很大并且移除的排列数量为$(nm)!$，即使对于微小的网格来说，这也是一个天文数字。 即使我们只考虑有效的前沿单元来进行修剪，状态空间仍然是指数的。 

关键的观察结果是成本函数是局部的并且在单元格和邻接关系上分解。 每个单元在被移除时始终贡献 1 的基本成本。 额外的成本来自于计算当时有多少邻居仍然是敌人。 我们可以不跟踪时间演化，而是将两个敌方单元之间的每个邻接重新解释为仅在处理移除顺序中的两个单元中的较晚一个单元时充电一次。 

这将问题从动态过程转变为静态计数问题：每个敌方细胞贡献一个，每对相邻的敌方细胞再贡献一个。

 | ---| ---| ---| ---|
 | 暴力模拟| 指数| O(纳米) | 太慢了 |
 | 计算细胞和邻接| O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 我们避免完全模拟移除，而是直接从初始网格计算贡献。 

1. 首先，扫描整个网格并计算有多少个单元格包含敌人。 这给出了基本成本贡献，因为每个敌方单元都被移除一次并且总是支付至少一个单位。 
2. 接下来，检查每个敌方单元并仅检查其右侧和下方的邻居。 对于每一对相邻的敌方单元格，我们都会计算一个额外的成本。 我们只向右和向下检查以避免重复计算，因为每个邻接都是无向的。 
3. 将基数和邻接数相加得到最终答案。 

我们只考虑向右和向下方向的原因是，两个敌方单元之间的每个邻接都恰好有两个端点，并且检查两侧会将同一对计数两次。 

### 为什么它有效

 将移除顺序视为任意但固定的。 每个单元仅贡献一次其基本成本。 现在考虑任意一对相邻的敌方单元 u 和 v。首先删除其中一个。 当这种情况发生时，另一个单元仍然是敌人，因此它为移除第一个单元提供了额外的成本。 当第二个细胞被移除时，第一个细胞已经消失并且没有任何贡献。 因此，每个相邻的对都贡献了一个单位总数，与顺序无关。 这使得总成本等于敌人单元的数量加上相邻敌人对的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
g = [list(map(int, input().split())) for _ in range(n)]

ones = 0
edges = 0

for i in range(n):
    for j in range(m):
        if g[i][j] == 1:
            ones += 1
            if i + 1 < n and g[i + 1][j] == 1:
                edges += 1
            if j + 1 < m and g[i][j + 1] == 1:
                edges += 1

print(ones + edges)
```代码直接实现了将答案分解为节点贡献和边贡献。 嵌套循环确保每个单元格都被访问一次。 支票`(i + 1, j)`和`(i, j + 1)`强制邻接对的唯一计数。 边界条件自然由索引检查处理，因此不需要额外的填充或哨兵网格。

 ## 边缘情况

 完全空的网格是自然处理的，因为扫描不会增加任一计数器，无需特殊逻辑即可产生零。 

单个敌方单元也可以正常运行，因为它为基数贡献 1，并且没有邻居来生成邻接贡献。 该算法不会尝试访问无效索引，因为所有邻居检查都受到保护。 

完全填充的网格是正确性最不明显的地方。 对于一个$n \times m$块中，每个内部邻接都通过向右和向下扫描精确计数一次，这与每个边缘贡献单个成本单位（无论移除顺序如何）的想法相匹配。
