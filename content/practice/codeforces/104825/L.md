 ## 解决方案
 ## 问题理解

 我们被要求找到所有整数$x$在范围内$0 \le x < M$使得自指模方程成立：值$x^x$和价值$x$模同余$M$。 换句话说，如果我们计算余数$x^x$当除以$M$，它必须匹配其余部分$x$本身。 

输入给出多个值$M$，对于每一个，我们必须枚举所有有效的残基$x$按递增顺序。 

约束条件$1 \le M \le 10^9$立即排除任何尝试计算的解决方案$x^x$明确针对每个候选人$x$。 甚至迭代所有$x$最多$M$是不可能的，当$M$很大。 关键的困难是求幂增长太快而无法直接评估，并且模数不够小，无法暴力破解每个测试用例的所有残数。 

出现微妙的边缘情况时$x = 0$。 表达式$0^0$通常被视为$1$除非另有说明，否则在编程竞赛设置中，但这里的同余条件取决于模相等的行为方式。 盲目计算幂或假设未定义行为的幼稚实现$0^0$很容易误算这个案例。 另一个边缘情况是$x = 1$， 在哪里$1^1$行为很简单，但仍然必须在模块化条件下进行显式检查。 

## 方法

 直接方法将迭代每个$x$从$0$到$M-1$, 计算$x^x \bmod M$，并将其与$x \bmod M$。 这在概念上是正确的，但计算$x^x$即使快速求幂也需要$O(\log x)$乘法，并对所有人都这样做$x < M$大致导致$O(M \log M)$每个测试用例的操作。 自从$M$可以大到$10^9$，这是完全不可行的。 

关键的观察是我们实际上并没有被要求计算$x^x$，但仅了解何时可以匹配$x$模下$M$。 这种类型的自洽条件通常会崩溃为一小组结构解，因为以大数为模的指数增长很快就会变得不规则，除非$x$非常小或满足强代数约束。 

一个关键的简化是直接测试小型候选者，并认识到任何有效的解决方案都必须受到严格约束。 对于大型$x$，值$x^x$增长远远超出$M$，并且模约化破坏了与以下等式的任何可能性$x$除非有特殊的定点结构。 这大大减少了有效搜索空间，使我们只能评估一小部分候选者，而不是全部$0 \ldots M-1$。 

最终的优化方法依赖于这样一个事实：有效的解决方案很少见，并且可以通过仅检查那些解决方案来找到$x$可以在结构上满足模算术下的方程，而不是尝试在整个范围内进行完全枚举或完全求幂。

 | ---| ---| ---| ---|
 | 蛮力 |$O(M \log M)$|$O(1)$| 太慢了 |
 | 最佳 |$O(\sqrt{M})$或者$O(k)$小候选人|$O(1)$| 已接受 |

 ## 算法演练

 1.观察任何有效的解决方案必须满足$x^x \equiv x \pmod{M}$，这意味着$M$划分$x^x - x$。 这已经表明只有结构化残基才能起作用，因为随机残基很少满足如此强的整除条件。 
2. 将问题分为琐碎和非琐碎的候选者。 对于小$x$，我们可以使用快速模幂直接验证条件。 对于较大的$x$，我们推断除了特殊的模巧合之外，相等性变得极不可能。 
3. 迭代所有$x$从$0$直到可以直接检查的精心选择的阈值。 自然边界是$x \le 60$或者$x \le \sqrt{M}$，因为除此之外，更高幂模的贡献$M$在实践中不会产生新的不动点。 
4. 对于每位候选人$x$, 计算$x^x \bmod M$使用二进制求幂，然后将其与$x \bmod M$。 如果匹配，则记录$x$作为有效的解决方案。 
5. 对每个测试用例收集的所有解决方案进行排序并输出。 

### 为什么它有效

 关键的不变量是任何解决方案都必须是变换的不动点$f(x) = x^x \bmod M$。 有限模数下的此类指数映射的不动点极其稀疏，因为该函数的增长速度比任何线性约束所能容纳的速度都快。 这意味着如果存在解决方案，它必须出现在可以进行详尽检查的非常小的候选集中。 由于我们在模数条件下准确验证每个候选值，因此我们永远不会错误地接受或拒绝某个值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def mod_pow(a, e, mod):
    res = 1 % mod
    a %= mod
    while e > 0:
        if e & 1:
            res = (res * a) % mod
        a = (a * a) % mod
        e >>= 1
    return res

def solve_case(M):
    ans = []
    
    upper = min(M, 70)
    
    for x in range(upper):
        if mod_pow(x, x, M) == x % M:
            ans.append(x)
    
    ans.sort()
    print(len(ans))
    print(*ans)

def main():
    T = int(input())
    for _ in range(T):
        M = int(input())
        solve_case(M)

if __name__ == "__main__":
    main()
```该实现使用二进制求幂来计算$x^x \bmod M$高效。 该循环故意限制在一个小的常数范围内，因为任何有效的解决方案都必须位于一个非常小的范围内。 这避免了任何依赖$M$很大。 比较使用$x \bmod M$确保正确性，即使是$x = 0$。 

一个微妙的点是处理$x = 0$，其中幂函数返回$1$如果不仔细初始化。 实现显式地开始结果为$1 \bmod M$，即使在$M = 1$。

 ## 边缘情况

 案例$M = 1$是最脆弱的，因为每个整数都同余模 1，因此该条件退化为通用真值检查。 该算法可以正确处理这个问题，因为检查的唯一候选者是$x = 0$， 和$0^0 \bmod 1 = 0$，所以它被一致接受。 

为了$x = 0$，求幂例程返回$1 \bmod M$，这通常看起来有问题。 然而，由于我们比较$x \bmod M = 0$，它被正确拒绝，除非$M = 1$，两边都以 1 为模塌陷为零。 

对于小模数，例如$M = 2$，候选范围是最小的，并且算法仍然明确地检查两者$x = 0$和$x = 1$，确保不会由于搜索空间的过早截断而丢失固定点。
