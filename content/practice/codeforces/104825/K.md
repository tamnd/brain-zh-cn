 ## 解决方案
 ## 问题理解

 我们得到一个字符串，它的作用类似于位置数字系统的描述，只不过它不是像十进制或二进制那样的固定基数。 相反，每个位置都有自己的“进位规则”。 如果某个位置包含数字 x，则该位置的行为类似于基数 x：一旦到达 x，它就会重置为 0 并将 1 传送到下一个位置。 

我们还给出了一个普通十进制形式的非负整数 d。 任务是在这个混合基数系统中表达 d，精确产生 m 位数字，如果不使用更高的位置，则包括前导零。 

描述这一点的一个有用方法是里程表，其中每个车轮都有不同数量的插槽，并且这些容量由输入字符串 s 的字符指定。 

约束 m ≤ 1000 意味着表示长度最多为一千位数字，因此每个数字处理一次数字的任何解决方案都足够快。 第二个参数 n 与计算本身无关，一旦读取就可以安全地忽略。 

这里最常见的失败情况是将系统视为具有单个碱基的正常碱基转换。 这会在 s = "29" 这样的输入上立即中断。 最低有效数字可能以 9 为基数，而下一个有效数字以 2 为基数，因此统一的基数解释会完全丢失结构。 

另一个微妙的问题是方向。 如果假设最左边的数字是最低有效位，则转换将相反。 例如，如果 s =“23”且 d = 5，则从左到右而不是从右到左解释会产生不同的余数，因为进位传播方向会改变位置权重。 

## 方法

 强力解释会模拟从 0 递增一个数字直到达到 d，每次都会更新混合基数数字。 每个增量需要传播最多 m 个位置的进位，因此最坏情况的成本与 d 乘以 m 成正比。 由于 d 可以大到 10^10，因此即使对于很小的 m，这也是完全不可行的。 

该系统的结构提出了更直接的解释。 从最低有效侧观察时，每个位置都独立地影响总数的扩展，类似于将数字转换为阶乘数字系统或任何通用混合基数系统。 我们可以使用重复除法直接提取数字，而不是模拟增量。 

关键的观察是字符串 s 定义了一系列基数，而 d 的表示正是 d 在这些基数下的混合基分解。 这使我们能够通过取余数并逐步减少 d 来计算每个数字。 

暴力方法会失败，因为它将数字视为随时间演变的问题，而最优方法则将其视为静态分解问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(d · 米) | O(米) | 太慢了 |
 | 混合基分解| O(米) | O(1) 额外 | 已接受 |

 ## 算法演练

1. 将字符串 s 的每个字符解释为其对应数字位置的整数基数。 最右边的字符是最不重要的位置，因为进位在标准位置系统中向左传播。 
2. 从给定的十进制数字 d 开始，它表示我们需要分解为混合基数表示的完整值。 
3. 从右向左遍历位置。 在每个位置 i，计算 d 除以 s[i] 的余数。 这确保了该数字在其本地基数约束内有效。 
4. 提取位置 i 的数字后，通过 s[i] 的整数除来减少 d。 该模型消除了当前位置的贡献并将剩余价值传播到更高的位置。 
5. 遍历时将所有提取的数字存储在数组中。 
6.处理完所有位置后，按原来的顺序从左到右输出数字。 

这样做的原因是每个位置在位置系统中贡献一个系数，其权重由其右侧所有碱基的乘积动态确定。 重复的取模和除法运算正是计算该系统中的系数，确保每个数字满足其局部约束，同时保留全局值。 

整个过程中保持的不变量是，在处理位置i开始时，变量d表示尚未分配给较低位置的剩余值，并且该剩余值总是可被已处理的碱基后缀定义的结构整除。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    m, n = map(int, input().split())
    s = input().strip()
    d = int(input().strip())

    bases = [int(c) for c in s]
    res = [0] * m

    for i in range(m - 1, -1, -1):
        b = bases[i]
        res[i] = d % b
        d //= b

    print("".join(map(str, res)))

if __name__ == "__main__":
    solve()
```实现完全遵循算法。 数组 res 将数字存储在其最终位置，因此我们通过直接写入索引 i 来避免在末尾反转。 循环从 m-1 处的最低有效位置运行到 0，确保正确的进位传播方向。 

一个常见的实现错误是从左到右处理，同时仍然使用模，这破坏了依赖结构。 另一个微妙的问题是忘记每个 s[i] 都是一个字符，并且必须在算术之前转换为整数。 

## 工作示例

 考虑 s = "243" 和 d = 17。我们将最右边的数字解释为基数 3，中间的数字解释为基数 4，左边的数字解释为基数 2。 

我们从右向左处理。 

| 位置 | 基地| 当前d | 数字（d% 基数）| 新 d (d // 基数) |
 | ---| ---| ---| ---| ---|
 | 2 | 3 | 17 | 17 2 | 5 |
 | 1 | 4 | 5 | 1 | 1 |
 | 0 | 2 | 1 | 1 | 0 |

 最终输出为112。 

该轨迹显示每个头寸如何消耗部分剩余价值，确保没有头寸超出其本地基础约束，同时保留总价值。 

现在考虑 s = "9999" 和 d = 123。这类似于具有固定长度的标准基数 9 表示。 

| 位置 | 基地| 当前d | 数字| 新d|
 | ---| ---| ---| ---| ---|
 | 3 | 9 | 123 | 123 6 | 13 |
 | 2 | 9 | 13 | 4 | 1 |
 | 1 | 9 | 1 | 1 | 0 |
 | 0 | 9 | 0 | 0 | 0 |

 输出是0146。 

这演示了当所有碱基都相等时，该方法如何自然地简化为标准碱基转换。

 ## 边缘情况

 当 d 为零时，每个模运算都会产生零，并且除法始终将其保持为零。 例如，当 s = "2345" 且 d = 0 时，每个步骤都会计算数字 0 并将 d 保留为 0，从而产生完全由零填充的输出。 

当 d 相对于早期碱基非常小但大于后来碱基时，较低的位置首先吸收所有值。 例如，当从右向左处理时，s = "234" 和 d = 2 会生成数字 [0, 0, 2]，因为只有最低有效基数会产生非零余数。 

当所有基数相等时，例如 s = "7777"，该算法的行为与固定宽度的基数 7 转换完全相同，确认混合基数概括了标准位置系统而不是替换它们。
