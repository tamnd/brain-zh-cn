 ## 解决方案

 ## 问题理解

 我们有两组点放置在圆周上$L$。 一套代表新郎的城堡，另一套代表新娘的宫殿。 每组都有准确的$n$点，并且每个点都位于圆边界上，以距固定原点的顺时针距离测量。 

有效的安排将每位新郎与一位新娘配对，从而在两组之间形成完美的匹配。 对于任何配对，新娘都会沿着圆圈到达指定的新郎的城堡，并且她总是选择两个可能的弧线中较短的一个。 配对成本被定义为所有新娘之间的最大旅行距离，任务是最小化这个最大值。 

这里的关键结构是，我们不是对距离求和，而是优化圆形度量空间上匹配的瓶颈。 

约束条件很大，最多可达$2 \cdot 10^5$点。 任何尝试显式测试匹配或构建成对距离矩阵的解决方案都会立即被排除，因为这意味着$O(n^2)$工作或更糟。 即使基于排序的二次构造也会太慢。 这促使我们寻求一个最多的解决方案$O(n \log n)$，可能涉及排序加上线性或对数可行性检查。 

圆形对称性产生了一种微妙的边缘情况。 如果我们天真地将圆视为线段$[0, L)$，我们错过了最佳的环绕匹配。 例如，当新郎靠近时$0$新娘就在附近$L - \varepsilon$，正确的答案应该将它们视为通过环绕相邻，但线性解释会迫使距离很长。 另一个问题是最佳匹配可能需要循环移位对齐； 任意固定一个顺序可能会错过真正的最小值。 

## 方法

 蛮力方法将尝试尝试新娘到新郎分配的所有排列。 对于每个排列，我们计算匹配对之间的最大圆形距离。 这是正确的，但立即不可行：有$n!$匹配，甚至评估一项成本$O(n)$，给出阶乘时间复杂度。 

关键的观察结果是成本函数相对于距离阈值是单调的。 假设我们固定一个值$x$并询问是否有可能将每个新娘与新郎相匹配，使得圆上的每个配对距离最多为$x$。 这将问题转化为可行性检查。 如果我们能够有效地测试可行性，我们就可以二分搜索答案。 

现在我们重点讨论如何检查固定的可行性$x$。 在一个圆圈上，新娘的位置$b$可以匹配任何位置位于弧长范围内的新郎$2x$以$b$，但更准确地说，在对圆进行线性化之后，每个新娘对应于圆上有效新郎位置的区间。 问题变成了二分匹配，其中每个新娘在排序的圆形结构上都有可接受的新郎的连续间隔。 

一旦两个数组都排序完毕，我们就可以通过复制位置（添加$L$到每个坐标）。 那么每个新娘的有效范围就变成了一个区间，我们需要将每个新娘分配给该区间内唯一的新郎。 这是一个经典的贪婪匹配问题：按排序顺序处理新娘，并始终分配最早可用的合适新郎。 

正确性来自于这样的事实：展开后，区间在线上是单调的，并且贪心赋值保留了满足未来约束的能力。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n!)$|$O(n)$| 太慢了|
 | 二分查找+贪婪可行性|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 对两个位置数组进行排序。 排序对于将结构强加在循环数据上是必要的，使我们能够一致地推断相对顺序。 
2. 通过添加来复制新郎位置$L$对于每个，形成一个大小的扩展数组$2n$。 这通过允许间隔以线性表示“跨越边界”来消除循环环绕问题。 
3. 对于固定候选答案$x$，为每个新娘计算距离内的新郎位置范围$x$在圆圈上。 展开后，每个新娘对应一个连续的区间$[l_i, r_i]$。 
4. 按区间的右端点对新娘进行排序。 这种顺序确保我们始终首先满足最受限制的新娘，从而防止以后发生冲突。 
5. 将指针保持在可用的新郎位置上。 对于按顺序排列的每位新娘，将指针前进到她的间隔内第一个未使用的新郎位置。 如果不存在，则候选人$x$无效。 
6.二分查找最小值$x$以便可行性检查成功。 

按右端点排序的原因是，首先分配较早结束的间隔可以最大限度地减少阻塞严格约束的机会，这是间隔调度变体的标准贪婪原则。 

### 为什么它有效

 展开圆圈后，固定阈值下的每个有效匹配都对应于从每个间隔中选择一个点，使得没有两个间隔共享相同的点。 这是一种二分匹配，其中一侧有间隔约束。 贪婪策略是正确的，因为在每一步中，选择最早可用的可行新郎都会为所有剩余间隔留下最大的灵活性。 任何延迟分配的替代选择只能减少未来可用的选项，而不会提高当前间隔的可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(x, a, b, L):
    n = len(a)
    
    # duplicate groom positions for circular wrap
    g = a + [v + L for v in a]
    
    # build intervals for brides
    intervals = []
    for bi in b:
        l = bi - x
        r = bi + x
        
        # normalize to linear doubled space
        # find valid range in g
        intervals.append((l, r))
    
    intervals.sort(key=lambda t: t[1])
    
    j = 0
    used = 0
    
    for l, r in intervals:
        while j < len(g) and g[j] < l:
            j += 1
        if j == len(g) or g[j] > r:
            return False
        used += 1
        j += 1
    
    return True

def solve():
    n, L = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    a.sort()
    b.sort()
    
    # binary search answer
    lo, hi = 0, L // 2
    
    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid, a, b, L):
            hi = mid
        else:
            lo = mid + 1
    
    print(lo)

if __name__ == "__main__":
    solve()
```代码首先对两组位置进行排序，这对于构造单调区间至关重要。 可行性函数试图将新娘与新郎职位的扩展列表进行贪婪地匹配，以实现循环环绕。 

二分查找将答案限制为$[0, L/2]$因为圆上的任何最短路径距离都不能超过圆周的一半。 

一个微妙的点是新郎使用了双重阵列。 这避免了当间隔跨越时必须显式处理模算术$0$边界。 指针`j`确保每个修饰最多使用一次，保留匹配约束。

 | --- | --- | --- | --- |

 这成功了，所以答案最多是 1。对于$x = 0$，无法匹配，因此结果为 1。 

这证实了该算法正确捕获了最短循环配对约束。

 ## 边缘情况

 当圆上的点几乎对映时，就会出现极端情况。 例如：```
2 100
0 50
25 75
```在这里，每个新娘与两个新郎在相反的方向上等距。 正确答案是 25，因为这是连接任何有效配对所需的最短弧。 该算法可以处理此问题，因为可行性区间对称扩展，并且仅当区间充分重叠时，贪婪扫描仍能找到有效分配。 

另一种情况是当所有点都聚集在圆的边界附近时，例如：```
3 10
8 9 0
1 2 3
```如果没有重复，跨越 0 边界的匹配就会失败。 对于双倍数组，环绕被表示为一个连续的段，贪婪赋值可以正确进行，就像在最佳点切割圆一样。
