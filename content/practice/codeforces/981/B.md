 ## 解决方案

 ## 问题理解

 两家公司各自拥有一组化学元素，其中每个元素都由一个大整数密钥标识。 某个元素的每次出现都会带来利润值，如果公司决定在展会上展示该元素，则可以赚取该利润值。 公司希望选择自己元素的子集以最大化总利润，但禁止他们在两个所选子集中提供相同的元素密钥。 

从更结构化的角度来看，每个元素键可能出现在一个公司、另一家公司或两者中。 如果它同时出现在两者中，冲突就会迫使我们决​​定最多允许哪一方使用它。 如果它只出现在一家公司，该公司可以根据其是否有利而自由地包含或排除它。 

目标是以最大化所选利润总和的方式解决共享密钥之间的所有冲突。 

约束总数最多为 200,000 个元素，这排除了将一组中的每个元素与另一组中的每个元素进行比较的任何解决方案。 在最坏的情况下，二次配对方法需要大约 10^10 次运算，这远远超出了时间限制。 关键的结构提示是两个集合之间的交互仅通过键相等而发生，因此所有推理都可以根据唯一元素索引进行本地化。 

总是选择每个键的两个冲突值中较高者的天真的贪婪想法似乎很有前途，但如果在不首先按键分组的情况下实现，则可能会被误用。 例如，如果单独处理同一键的重复项而不是聚合，则可能会错误地为同一元素标识选择多个贡献，这违反了问题条件。 

当密钥仅出现在一家公司时，就会发生另一种微妙的失败情况。 仅处理相交键的粗心实现可能会忘记完全包含这些独特元素，从而损失保证的利润。 

## 方法

 强力方法会尝试独立考虑每个元素键，并为每个可能的分配决定是否将其分配给 ChemForces、TopChemist，或者两者都不分配。 如果我们想象 k 个共享密钥，这将成为每个密钥的三元决策，从而导致 3ᵏ 种可能性。 即使在中等 k 值下，这也会发生组合爆炸并且是不可行的。 

关键的观察是决策之间的唯一耦合是每个相同的元素索引。 一旦我们按键对所有出现的事件进行分组，每个键就成为一个独立的决策单元。 对于给定的密钥，我们要么采用 ChemForces 的贡献，要么采用 TopChemist 的贡献，或者两者中的最大值（如果两者都存在）。 

这将整个问题简化为一个简单的聚合任务：对于每个不同的键，计算可实现的最佳贡献并将其求和。 

暴力破解会失败，因为它处理全局交互，而问题实际上完美地分解为独立的每个键选择。 最佳解决方案直接利用这种分解。

 ## 算法演练

 1. 读取两家公司的所有元素并按索引值对它们进行分组。 对于每个密钥，存储从 ChemForces 看到的最佳利润和从 TopChemist 看到的最佳利润。 这是必要的，因为每个公司在内部保证不同的密钥，因此每个公司的每个密钥最多存在一个值。 
2. 对于两家公司密钥联合中的每个密钥，确定其对最终答案的贡献。 如果某个key只存在于一家公司，则直接取其值。 如果两者都存在，则取两个值中较大的一个。 
3. 对所有键上选择的这些贡献进行求和。

关键的决定是每个键的最大值，它确保没有冲突的键被计算两次，同时仍然保留最佳可能的选择。 

### 为什么它有效

 每个密钥都独立于所有其他密钥，因为唯一的限制是不能同时从两家公司选择相同的密钥。 没有跨键限制。 一旦我们隔离了一个密钥，该密钥的最优决策就不会影响任何其他密钥，这保证了局部最优选择组合成全局最优解决方案。 这是一个经典的可分离性属性：目标函数在键上是可加的，并且约束不会耦合不同的键。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
best = {}

for _ in range(n):
    a, x = map(int, input().split())
    best[a] = x  # ChemForces values

m = int(input())
for _ in range(m):
    b, y = map(int, input().split())
    if b in best:
        best[b] = max(best[b], y)
    else:
        best[b] = y

print(sum(best.values()))
```第一个循环使用 ChemForces 的值初始化字典。 第二个循环要么为仅限 TopChemist 的元素插入新键，要么通过获取最大值更新现有键，从而正确解决冲突。 

最终总和汇总了每个密钥的最佳贡献。 

一个常见的实施陷阱是忘记每个公司的输入已经保证了其内部密钥的唯一性。 这使我们能够为每个公司的每个键存储一个值，而无需进一步聚合。 另一个微妙的点是确保我们永远不会通过将两个值相加来重复计算共享密钥； 相反，我们会覆盖或比较。

 ## 边缘情况

 一个关键的边缘情况是一家公司没有要素。 在这种情况下，答案就是其他公司价值观的总和。 该算法自然地处理这个问题，因为所有密钥仅来自一侧并直接添加。 

Another case is when all keys overlap. 对于输入：```
2
1 5
2 3
2
1 4
2 10
```随着键 1 变为 max(5,4)=5，键 2 变为 max(3,10)=10，字典不断演变，产生 15。这证实了更新永远不会累积这两个值。 

最终的边缘情况是 n 和 m 的值非常大，每个值都达到 100,000。 基于字典的聚合确保每个元素的恒定时间处理，因此即使完全重叠输入也保持线性时间并且不会降级。
