 ## 解决方案

 ## 问题理解

 我们得到一个正整数序列，表示按固定顺序排列的书籍。 每本书都有一个价值，我们必须将这个序列分成正好 k 个连续的段。 每个段对应一个书架，书架的值是该段中值的总和。 

选择分区后，我们计算 k 段总和，然后对所有这些总和进行按位 AND 运算。 目标是选择分区以使最终的 AND 值尽可能大。 

结构很重要：我们不会重新排序书籍，只是决定它们之间的剪切位置。 每本书必须恰好属于一个段，并且任何段都不能为空。 

约束 n ≤ 50 和 k ≤ n 立即表明三次甚至适度嵌套的二次解可能是可以接受的，但任何未经修剪的 n 指数都太大了。 涉及对位置和段数进行动态规划的解决方案是合理的，因为状态空间很小：最多 50 个位置和 50 个段。 

尝试所有分区的简单方法会导致组合爆炸。 在 n−1 个间隙中选择 k−1 个切割的方法数量已经足够多，使得在最坏的情况下暴力破解是不可行的。 

一些微妙的边缘情况很重要。 

一种是当 k = n 时。 那么每个段都只有一本书，答案只是所有单独值的按位与。 

另一种是当k = 1时。那么只有一个段，答案是所有元素的和。 粗心的 DP 实现常常会忘记正确初始化这种情况。 

一个更有趣的情况是当值很大但位稀疏时。 因为 AND 是按位运算，所以较高位主导答案，并且不正确的分组可能会默默地删除本可以保留的位。 

## 方法

 蛮力的想法是枚举在 n−1 个位置之间放置 k−1 个切割的所有方法，计算每个分区的段和，然后计算这些和的 AND。 对于每个分区，计算总和需要 O(n)，并且有 C(n−1, k−1) 个分区。 即使 n = 50，这也会变得巨大，在最坏的情况下很容易超过 10^13 配置。 

关键的观察是，我们在计算段和时只关心前缀和，并且分区结构仅取决于切割位置。 这表明对前缀的动态编程。 

我们定义一个 DP，在其中决定如何将前 i 个元素拆分为 j 个段。 关键的想法是，一旦我们确定了最后一个剪切位置，最后一段的值就可以通过前缀和得知，并且所有先前的段都是独立的。 

因此，我们可以尝试每个可能的先前切割位置 p < i，并使用 (p+1 ... i) 中的元素之和从 dp[p][j−1] 过渡到 dp[i][j]。 最终答案是所有 dp[n][k] 状态上最大可能的按位与。 

我们为每个 dp 状态存储的不是单个值，而是可实现的最佳 AND 结果。 由于 AND 在添加更多约束只会减少位数的意义上是单调的，因此 DP 仍然有效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(C(n,k) · n) | O(C(n,k) · n) | O(n) | 太慢了|
 | 最佳DP | O(n^2k) | O(n^2k) | O(n·k) | 已接受 |

 ## 算法演练

 我们使用前缀和来计算段和，时间复杂度为 O(1)。 令 pref[i] 为前 i 本书的总和。

1. 构建前缀和，使得从 l 到 r 的任何段和为 pref[r] − pref[l−1]。 这允许恒定的时间段评估。 
2. 将 dp[i][j] 定义为将前 i 本书分割为 j 个非空连续段时段和的按位与的最大可能值。 
3. 初始化 dp[0][0] =（所有位设置，概念上为 2^50−1）。 这表示尚未选择任何分段。 
4. 对于从 1 到 n 的每个 i，设置 dp[i][1] = pref[i]，因为对于一个段，该值是固定的。 
5. 对于从 2 到 k 的每个 j，以及从 j 到 n 的每个 i，尝试从 j−1 到 i−1 的所有可能的最后切割位置 p。 
6. 对于每个转换，计算segment_sum = pref[i] − pref[p]，并更新：

 dp[i][j]=max(dp[i][j],dp[p][j−1]&segment_sum)。 

AND 将之前的最佳结构与新的细分贡献相结合。 
7. 最终答案是dp[n][k]。 

我们在所有可能的先前剪切位置上循环 p 的原因是，最后一段取决于我们剪切的位置，并且不同的选择可以在 AND 运算后保留不同的位模式。 

### 为什么它有效

 在每个状态 dp[i][j] 处，我们考虑了将长度 i 的前缀划分为 j 段的所有可能方法。 任何有效的分区必须以某个最后的切割位置 p 结束。 对于该固定 p，前缀 p 上可实现的最佳结果已存储在 dp[p][j−1] 中。 用最后一段扩展它会产生一个有效的候选值，并且在所有 p 上取最大值确保我们探索每个有效的分区。 由于 AND 在每个步骤中一致应用，因此每个 dp 状态准确地表示该前缀和段计数可实现的最佳按位结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

pref = [0] * (n + 1)
for i in range(n):
    pref[i + 1] = pref[i] + a[i]

NEG = -1  # all bits set in Python two's complement representation is not needed explicitly

dp = [[-1] * (k + 1) for _ in range(n + 1)]
dp[0][0] = (1 << 60) - 1

for i in range(1, n + 1):
    dp[i][1] = pref[i]

for j in range(2, k + 1):
    for i in range(j, n + 1):
        best = -1
        for p in range(j - 1, i):
            if dp[p][j - 1] == -1:
                continue
            seg = pref[i] - pref[p]
            val = dp[p][j - 1] & seg
            if val > best:
                best = val
        dp[i][j] = best

print(dp[n][k])
```前缀和数组允许我们在恒定时间内计算任何段总和，避免在转换内重复重新计算。 DP 表存储每个前缀和段计数的最佳可实现 AND 结果。 j、i 和 p 上的三重循环在 n ≤ 50 下是安全的。 

初始化 dp[i][1] = pref[i] 编码了这样一个事实：对于单个书架，没有选择。 使用 -1 作为无效状态确保我们不会传播不可能的分区。

 对于 i = 3：

 p=1: 1 & 9 = 1

 p=2: 3 & 7 = 3

 p=4: 10 & 5 = 0

 dp[5][2]=0。

此跟踪显示不同的分割点如何保留不同的位，以及当段很大且混合时 AND 如何快速折叠值。

 ## 边缘情况

 一个关键的边缘情况是当 k = n 时，这意味着每本书都形成自己的部分。 对于输入：```
3 3
5 1 7
```唯一有效的分区是 [5]、[1]、[7]。 DP 正确初始化 dp[i][1]，更高的段转换迫使每次切割都在精确位置，产生段和 5、1、7 以及最终结果 5 & 1 & 7 = 1。 

另一个边缘情况是 k = 1：```
4 1
2 3 4 5
```没有分裂。 dp[n][1]直接变成总和14。任何超出j=1的DP状态都是无关紧要的，算法自然会避免它们。 

第三种情况涉及位结构很重要的大值：```
4 2
8 4 2 1
```不同的分割保留不同的高位，但 DP 会探索所有切割位置，确保选择最佳组合。
