 ## 解决方案
 ## 问题理解

 给定一棵无向树，我们必须将其所有边拆分为一组简单路径，以便每条边都属于一个路径。 额外的要求是全局性的和限制性的：如果我们选择这些路径中的任意两条，它们必须至少共享一个公共顶点。 

所以我们并不是随意分解一棵树。 我们在路径集上强制采用非常强大的交叉结构，同时仍然精确地覆盖每个边缘一次。 

输入是最多有 100000 个顶点的树，因此任何解决方案都必须本质上是线性或接近线性的。 任何试图枚举路径、测试分解或重复重新计算连接的东西都将无法生存，因为即使$O(n \log n)$具有沉重的常数已经是边缘。 

第一个微妙的问题是理解“树中成对相交的路径”在结构上真正的作用力。 在一般图中，成对交集并不意味着全局交点。 然而，在树中，路径的行为方式要严格得多。 如果每对简单路径相交，它们必须至少共享一个公共顶点。 如果情况并非如此，人们可以选择两条在不同子树中分叉的路径，并构建第三条路径，避免它们重叠，从而与两两相交相矛盾。 

因此，我们尝试构建的真正结构是一种分解，其中所有路径都经过单个顶点，该顶点充当通用交点。 

当树是路径时，会出现微妙的边缘情况。 那么唯一有效的分解是覆盖所有边的单个路径。 如果我们错误地尝试将其分割成较小的线段，则两端的两个线段将不会相交，因此答案将无效，除非我们将所有内容都保持在一个片段中。 

另一种故障模式是具有不以单个节点为中心的分支结构的树。 例如，每个分支都很长的三阶顶点可能会破坏任何强制形成单个相交顶点的尝试，因为分解需要将分支拆分为多个链，而这些链不能在考虑边不相交的同时全部通过单个共享顶点。 

因此，任务是确定这样的“通用中心”是否存在，如果存在，则显式构造一个有效的分区。 

## 方法

 暴力方法会尝试枚举将边划分为简单路径的所有可能方法，然后检查相交条件。 即使忽略分区的组合爆炸，将树分割成路径的方法数量也与边的数量呈指数关系，因为每条边都可能决定路径的开始或结束位置。 为了$n = 10^5$，这是完全不可行的。 

关键的简化来自相交约束。 一旦我们认识到所有路径必须共享一个公共顶点$c$，问题就变成了该顶点周围的局部问题。 每条有效路径都被限制通过$c$，这意味着每条路径都由两个根到节点的段组成，这两个段在$c$，或以简并形式，从以下位置开始的单个片段$c$。 

这将问题转化为理解树在这个特殊顶点扎根时的样子$c$。 每条边都被分配给一条从以下位置开始的路径：$c$然后走到树下。 由于路径不能分支，因此结构如下$c$必须表现得像不相交的链。 如果任何子树包含远离的分支节点$c$，在不违反边不相交的情况下，分支不能容纳在单个简单路径中。 

所以问题就简化为寻找一个顶点$c$这样删除后树的每个连接组件$c$是一个简单的路径图。 一旦找到这样的顶点，每个组件都可以作为一条链进行遍历，并变成一条从$c$。

 | --- | --- | --- | --- |
 | 枚举所有分解 | 指数| O(n) | 太慢了|
 | 中心化建设| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们通过搜索合适的中心顶点然后分解它周围的树来构建解决方案。 

1. 迭代所有顶点并将每个顶点视为潜在中心。 为了使顶点有效，删除它后的每个连接组件不得包含任何分支，这意味着该组件中的任何节点在原始树中的度数都不能大于 2。 
2. 对于选定的候选顶点$c$，我们暂时忽略它并检查每个邻居的子树。 我们确保在每个子树中，每个节点最多有两个位于该子树结构内的关联边。 这保证了每个子树都是链而不是分支结构。 
3.一旦成为有效中心$c$找到后，我们将树根设在$c$并开始修建道路。 每次我们进入邻居子树时，我们都会沿着唯一的链向外，直到到达叶子或分支边界，并沿途收集节点。 
4. 每次这样的遍历都会产生一条从$c$并向外延伸。 由于子树是链，因此该遍历是确定性的，并且一次覆盖该组件中的所有边。 
5. 我们输出所有这样的路径。 每条边都属于一个子树链，因此保留了边不相交，并且每条路径都包括$c$，保证所需的两两交集。 

关键的不变量是选择一个有效的中心后$c$，每个连通分量$G - c$是一个路径图。 这确保了这些组件中的每条边恰好属于一个线性链，从$c$，因此没有分支会强制重用或分割路径。 因为每条路径都包含$c$，任意两条路径至少相交于$c$，满足全局条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n)]

for _ in range(n - 1):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    g[a].append(b)
    g[b].append(a)

deg = [len(g[i]) for i in range(n)]

# find candidate center: node such that all nodes except it have deg <= 2
center = -1
for v in range(n):
    ok = True
    for u in range(n):
        if u != v and deg[u] > 2:
            ok = False
            break
    if ok:
        center = v
        break

if center == -1:
    print("No")
    sys.exit()

visited = [False] * n
visited[center] = True

paths = []

def dfs(u, path):
    visited[u] = True
    path.append(u)
    nxt = -1
    for v in g[u]:
        if not visited[v]:
            nxt = v
            break
    if nxt == -1:
        paths.append(path)
        return
    dfs(nxt, path)

for v in g[center]:
    if not visited[v]:
        dfs(v, [center])

print("Yes")
print(len(paths))
for p in paths:
    print(p[0] + 1, p[-1] + 1)
```该实现首先计算度数并搜索可以用作全局交点的顶点。 这里强制的条件是没有其他顶点的度大于2，这确保去除中心后形成的每个子树都是简单链。 

固定中心后，每个未访问的邻居子树都会按照唯一可用的前进方向进行深度优先遍历。 因为内部节点在子树中最多有两个未使用的边，所以这种遍历永远不会分支，因此它会产生一条干净的路径。 每条路径都由其端点记录，这足以用于输出。 

一个微妙的点是我们总是从中心开始 DFS 并立即扩展到每个子树。 这保证了每条构造的路径都包含中心顶点，这是相交条件成立的结构原因。

4

```这已经是单链了。 

| 步骤| 当前节点 | 行动| 形成的路径|

 整棵树是一条路径，因此它成为一条覆盖所有边的分解路径。 这基本上满足了边缘覆盖和相交条件。 

### 示例 2

 考虑一棵分支树：```

1 2
2 3
2 4
3 5
```| 步骤| 中心尝试| 子树结构 | 有效的？ |

该迹线表明，候选中心下方的分支阻止构建单个线性路径分解。

 ## 边缘情况

 路径形树测试算法是否避免过度分裂。 在这种情况下，除了端点之外的每个节点的度数都是 2，因此任何有效的中心都可以工作。 DFS 恰好生成覆盖整个结构的一条路径，并且输出仍然有效，因为只有一条路径，因此交集条件不成立。 

星形树检查中心选择是否正确识别集线器。 所有叶子的度数都是 1，因此只有中心的度数高。 从中心开始的每个 DFS 立即终止，产生单边路径，所有路径共享中心顶点，满足条件。 

具有远离所选中心的单个分支节点的混合树表明失败。 度数条件将其过滤掉，因为分支节点将违反“所有其他节点的度数≤2”的要求，确保算法正确输出“否”，而不是尝试无效的分解。
