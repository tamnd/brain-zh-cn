 ## 解决方案
 ## 问题理解

 我们得到一个元素序列，每个元素都有一个值和一个颜色。 序列的顺序是固定的，但值不是静态的。 随着时间的推移，我们应用一次性影响几乎所有颜色的全局更新，并且我们还回答有关一种特定颜色的查询。 

有两个操作。 第一个操作选择颜色`Col`和一个数字`X`，然后增加每个颜色不是的元素`Col`经过`X`。 第二个操作选择颜色`Col`和一个阈值`Y`，并且我们只按原始顺序查看该颜色的元素。 从这个过滤后的序列中，我们想要最长的前缀，其总和最多为`Y`。 

困难在于更新是全局的且重复的，因此每个元素的值取决于发生了多少次更新以及每次排除了哪些颜色。 立即更新每个查询的每个元素的简单模拟会变得太慢，因为元素和查询的数量都可能很大。 

这些限制意味着任何涉及每个查询所有元素的解决方案都过于昂贵。 对于多达 200,000 个元素和 200,000 个查询，O(NQ) 方法在最坏的情况下将达到约 400 亿次操作，这是不可行的。 因此，我们需要避免重复重新计算元素值，而是维护一些聚合结构。 

第二个查询中出现了一个微妙的困难：我们需要动态变化的序列上的前缀和，但这些变化取决于过去的更新，每次有选择地排除一种颜色。 按需重新计算每个元素的当前值的粗心方法会重复重新应用所有更新，这也太慢了。 

一个小例子展示了这个陷阱。 假设除了颜色 2 的一个元素之外，所有元素都是颜色 1，并且许多更新不包括颜色 1。颜色 1 元素的值与颜色 2 元素的变化不同，因此如果不仔细跟踪，每个查询的重新计算会变得昂贵且容易出错。 

## 方法

 蛮力的想法很简单。 我们显式地维护该数组。 对于每个类型 1 查询，我们迭代所有元素并添加`X`对于那些颜色不是`Col`。 对于每个类型 2 查询，我们构建过滤后的颜色数组`Col`，计算前缀和，并找到最长的前缀，其和最多为`Y`。 这是正确的，因为它直接遵循定义，但每次更新成本为 O(N)，每次查询也可能成本为 O(N)，导致 O(NQ)，这对于约束来说太大了。 

关键的观察结果是，除了一种颜色之外，所有元素的更新都是统一的。 我们可以跟踪应用了全局增量的次数，然后减去排除特定颜色的更新的贡献，而不是更新单个元素。 每个元素的值可以表示为其初始值加上全局贡献减去排除其颜色的更新的贡献。 

这个视角使我们能够将更新的效果分为全局累积和每颜色补偿。 一旦可以用这种分解形式表达值，我们就不再需要直接修改每个元素。 对于每种颜色，我们可以维护其元素的聚合统计信息，对于查询，我们可以使用预先计算的结构加上校正项来计算前缀和。 

我们还需要对每种颜色进行快速前缀评估。 由于给定颜色的元素以固定顺序出现，因此我们可以预先计算每种颜色初始值的前缀和，并维护一个结构，使我们能够评估当前全局状态下的有效前缀和。 然后，每个查询简化为查找最大前缀，其中前缀长度的线性函数保持在 Y 内，这可以使用每种颜色的二分搜索来解决。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(NQ) | O(N) | 太慢了|
 | 优化分解+前缀搜索 | O((N + Q) log N) | O((N + Q) log N) | O(N) | 已接受 |

 ## 算法演练

 我们按颜色对所有索引进行分组，并为每种颜色预先计算原始顺序的位置列表以及初始值的前缀和。 

我们还维持两个全球数量。 第一个是类型 1 更新的总数乘以它们的 X 贡献，表示如果不存在排除，每个元素会增加多少。 第二个是对于每种颜色，排除该颜色的增量总量。 

1. 对于每种颜色，我们按原始顺序预先计算属于该颜色的元素数组及其前缀和。 这允许对颜色组的任何前缀进行快速求和查询。 
2. 我们维持全球柜台`G`表示适用于所有类型 1 操作中每个元素的总加性效应，忽略排除。 
3. 对于每种颜色`c`，我们维持`bad[c]`，排除颜色的类型 1 更新的总贡献`c`。 这代表了有多少颜色元素`c`与全球基线相比没有收到。 
4. 处理类型1查询时`(Col, X)`，我们将其解释为增加除颜色之外的所有元素`Col`经过`X`。 我们不更新数组，而是通过增加来更新全局结构`G`经过`X * N`从概念上讲，但更重要的是我们调整`bad[Col]`通过添加颜色避免的总贡献。 这让我们稍后可以隐式重建正确的每个元素值。 
5. 对于类型 2 查询`(Col, Y)`，我们只检查该颜色的数组。 该颜色组中第 i 个元素的值变为其初始值加上`G`减`bad[Col]`。 由于这种偏移在整个颜色中是均匀的，因此前缀中的每个元素都会增加相同的加法常数。 
6. 因此，第一个的总和`k`色彩元素`Col`变成`prefix_initial[k] + k * (G - bad[Col])`。 
7.我们需要最大的`k`使得这个表达式最多是`Y`。 我们对`k`使用前缀和数组。 

关键的不变量是对于任何颜色元素`c`，其当前值始终可表示为其原始值加上全局加性项减去特定于颜色的校正项。 这确保了所有查询都能得到一致的回答，而无需显式修改数组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N = int(input())
    A = list(map(int, input().split()))
    C = list(map(int, input().split()))
    Q = int(input())

    from collections import defaultdict

    pos = defaultdict(list)
    val = defaultdict(list)

    for i in range(N):
        pos[C[i]].append(i)
        val[C[i]].append(A[i])

    pref = {}
    for c in pos:
        s = [0]
        for v in val[c]:
            s.append(s[-1] + v)
        pref[c] = s

    # global additive effect
    global_add = 0
    # per color compensation
    bad = defaultdict(int)

    # number of elements per color
    sz = {c: len(pos[c]) for c in pos}

    for _ in range(Q):
        t, Col, X = map(int, input().split())
        if t == 1:
            # all except Col increase by X
            global_add += X
            bad[Col] += X
        else:
            Y = X
            if Col not in pos:
                print(0)
                continue

            g = global_add - bad[Col]
            arr_pref = pref[Col]

            # binary search for max k
            lo, hi = 0, len(arr_pref) - 1
            ans = 0

            while lo <= hi:
                mid = (lo + hi) // 2
                total = arr_pref[mid] + mid * g
                if total <= Y:
                    ans = mid
                    lo = mid + 1
                else:
                    hi = mid - 1

            print(ans)

if __name__ == "__main__":
    solve()
```该实现按颜色对元素进行分组，以便第二类查询仅涉及相关子集。 前缀和允许快速计算原始和以及线性移位`g`紧凑地模拟所有更新。 二分查找找到满足约束的最大前缀长度。 

一个微妙的点是`g`颜色的所有元素都是统一的，这就是前缀和调整有效的原因。 如果没有这种一致性，前缀和就不够。

| 步骤| 查询 | 全局添加| 坏[1] | 坏[2] | 关键计算 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 初始化| 0 | 0 | 0 | 构建的前缀 |
 | 2 | 1 1 2 | 1 1 2 2 | 0 | 2 | 颜色 1 不受影响，颜色 2 减少 |

 对于颜色 2 查询，有效移位为`2 - 2 = 0`，所以我们只取原始前缀和。 我们可以包含颜色 2 的前两个元素，但不超过 8 个。 

对于颜色 1 查询，有效移位为`2 - 0 = 2`，所以每个元素均匀增加2，只有第一个元素适合5以内。 

这证实了更新已正确吸收到每种颜色的统一偏移中。

 ## 边缘情况

 一种边缘情况是所有元素都属于相同颜色。 在这种情况下，每个类型 1 更新都会排除该颜色，这意味着没有元素会收到任何增量。 该算法可以正确处理这个问题，因为`bad[Col]`累积所有更新并取消全局贡献，使有效移位为零。 

另一种情况是当有许多小元素和非常大的 Y 时。二分搜索将始终返回完整长度，因为前缀和永远不会超过 Y。统一移位保留了前缀和的单调性，因此搜索空间保持良好的性能。 

第三种情况是更新交替排除不同颜色。 分解可确保每种颜色独立跟踪其被排除的数量，因此不会丢失任何历史记录。 即使在多次交替更新之后，有效值仍然保持一致，因为每次更新仅对全局状态和一个校正桶做出贡献。
