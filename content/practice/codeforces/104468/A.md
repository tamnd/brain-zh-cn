 ## 解决方案
 ## 问题理解

 我们有两个长度相同的数组。 在每个位置，我们都会看到一对值，并且我们可以选择在任何选定位置内交换这两个值。 执行一些交换后，目标是使两个结果数组本身不包含重复值。 

另一种看待操作的方式是，每个索引贡献一对值，我们可以决定是否保持该对不变或翻转它。 选择翻转后，第一个分量形成一个数组，第二个分量形成另一个数组，并且两个数组都必须成为集合。 

输出是所需翻转的最小次数，如果没有选择翻转可以避免重复，则输出是不可能的。 

这些约束允许跨测试用例最多包含 100,000 个总元素。 这立即排除了任何尝试所有索引子集或模拟指数选择的解决方案。 我们需要每个测试用例接近线性的东西，很可能基于关于值之间冲突的计数和结构推理。 

当两个数组中存在重复项并且单个值在不兼容的位置出现太多次时，就会出现幼稚故障模式。 例如，如果一个值在两个位置上以多对形式出现，但翻转选择无法分离所有出现的值，我们可能会错误地假设存在局部修复。 

另一个微妙的问题是假设贪婪地修复每个值的重复项是独立有效的。 例如，如果值 5 出现在多个对中，则独立解决其冲突可能会破坏另一个值的唯一性，因为翻转会同时耦合两个值。 

## 方法

 强力方法会将每个索引视为二元决策：交换或不交换。 这给出了 2^N 种配置。 对于每个配置，我们检查两个数组是否包含所有不同的值。 检查有效性的成本为 O(N)，因此总复杂度变为 O(N·2^N)，即使对于 N = 20，这也是不可行的。 

关键的观察是该结构不是任意的：每个索引恰好为第一个数组贡献一个值，为第二个数组贡献一个值，并且交换仅翻转一对的分配。 因此，每个索引都是两个标签的二进制分配，只有当相同的值被分配给同一侧两次时才会出现冲突。 

这将问题转化为类图结构上的约束系统，其中每个值每边最多只能出现一次。 我们不是全局搜索分配，而是对每个值进行推理：每个值出现在一定数量的对中，并且每次出现都有助于选择侧面位置。 如果某个值出现 k 次，则这 k 次出现必须进行分布，以便最多 1 次出现在第一个数组中，最多 1 次出现在第二个数组中。 

由此，我们得出一个必要条件：所有值对中总共出现的次数不能超过两次。 如果出现三次，则根据鸽巢原理，无论交换如何，至少两次出现都必须落在同一侧，从而使该条件不可能出现。 

一旦可行性得到保证，我们就通过强制一致的分配来最大限度地减少交换：每当一个值出现两次时，这些出现必须分布在不同的一侧。 这导致了一种确定性的选择结构，其中每个位置根据是否解决冲突贡献零或一次强制交换。

 ## 算法演练

 我们独立处理每个测试用例。

1. 对两个数组中出现的所有值构建频率图。 如果任何值出现两次以上，我们立即得出答案是不可能的。 这是因为两个数组只能各自保存一个值的一个副本。 
2. 对于每个位置，将其解释为无序对 (a, b)。 如果 a 等于 b，则在决策后该值必须在同一侧出现两次，这是不可能的，因为无论交换如何，两个副本都会进入同一个数组。 因此，这样的立场立即迫使不可能。 
3. 我们现在根据每个值出现的次数对其进行分类。 恰好出现两次的值是唯一会创建约束的值，因为它们必须拆分到两个数组中。 
4. 我们为每个事件指定一个所需的方向。 对于一对 (a, b)，我们决定它应该保留还是交换，以便将出现两次的每个值分开：一次出现将 a 贡献给第一个数组，另一个出现将其贡献给第二个数组。 
5. 我们贪婪地遍历索引，跟踪每个值已经被分配给第一个数组的次数。 如果指定当前方向的任何值在一侧超过一次出现，我们会尽可能翻转它。 
6. 每次我们被迫翻转一对以避免违反唯一性时，我们都会增加操作计数。 

贪婪步骤背后的原因是，每个值在每一侧都独立地需要一次出现，一旦一侧已经拥有其配额，任何未来的出现都必须转到另一侧，如果当前分配不正确，则强制进行交换。 

### 为什么它有效

 关键的不变性是，在每一步中，对于每个值，我们都认为它在处理的索引中的每个构造的数组中最多出现一次。 由于每个值在全局中最多出现两次，一旦出现一次被固定在一侧，其余的出现就没有灵活性，必须占据另一侧。 这消除了任何分支决策，并使分配具有确定性直至强制翻转。 该算法永远不会产生本来可以避免的冲突，因为只有当值违反唯一性约束时才会触发每次翻转。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = []
        b = []
        for _ in range(n):
            x, y = map(int, input().split())
            a.append(x)
            b.append(y)

        freq = {}
        for i in range(n):
            freq[a[i]] = freq.get(a[i], 0) + 1
            freq[b[i]] = freq.get(b[i], 0) + 1

        ok = True
        for v in freq:
            if freq[v] > 2:
                ok = False
                break

        if not ok:
            print(-1)
            continue

        # track assignment counts
        cntA = {}
        cntB = {}
        ops = 0

        for i in range(n):
            x, y = a[i], b[i]

            # if same value, impossible (would duplicate in both arrays)
            if x == y:
                ok = False
                break

            # try keep orientation first: x->A, y->B
            ca = cntA.get(x, 0)
            cb = cntB.get(y, 0)

            if ca < 1 and cb < 1:
                cntA[x] = ca + 1
                cntB[y] = cb + 1
            else:
                # must swap
                ops += 1
                cntA[y] = cntA.get(y, 0) + 1
                cntB[x] = cntB.get(x, 0) + 1

        if not ok:
            print(-1)
        else:
            print(ops)

if __name__ == "__main__":
    solve()
```该解决方案首先使用两个数组的频率计数来检查可行性，因为任何值超过两次出现都会导致无法将其唯一地分配到两个不同的数组中。 

然后它模拟每对的贪婪分配。 最初假设每对将其第一个值贡献给第一个数组，将第二个值贡献给第二个数组。 如果该分配超出了每侧每个值出现一次的允许计数，则算法会交换该对并计算一次操作。 

一个微妙的细节是早期拒绝相等的配对。 如果一对是 (x, x)，则交换不会执行任何操作，并且两个数组都将在该位置包含 x，从而立即违反唯一性。 

贪婪决策之所以有效，是因为每个值最多总共出现两次，因此一旦使用了一侧，就会强制其余的出现。 这可以防止后来的冲突使先前的选择无效。

 ## 边缘情况

 一个重要的边缘情况是，一个值恰好出现两次，但两次出现最初都通过天真的贪婪选择分配给同一侧。 在这种情况下，算法必须强制对其中一个进行交换； 否则最终的数组将包含重复项。 贪婪规则确保这种情况不会持续存在，因为第二次出现将检测到第一面已经满了该值。 

另一个边缘情况是像 (x, x) 这样的自对。 该算法立即拒绝它，因为交换不会改变贡献，并且会在该索引处的两个数组中引入重复项。 

第三种边缘情况是多个值形成重叠约束，例如对 (1,2)、(2,3)、(3,1)。 该算法通过顺序分配来解决此循环，并且每次强制交换对应于打破一个循环边缘，确保所有值最终正确分割而不超过其每侧限制。
