 ## 解决方案
 ## 问题理解

 我们正在研究长度的排列$N$，所以每个有效的排列都是对来自的数字的重新排序$1$到$N$。 我们唯一关心的结构属性是一个位置是否$i$是血统，意思是$P_i > P_{i+1}$。 这些位置很特殊，因为它们正是从左到右阅读时排列下降的“断点”。 

我们得到了一组$S$的指数。 该条件限制了允许下降的位置：如果一个位置$i$是一个下降，那么$i$必须属于$S$。 同样，所有外部位置$S$必须被迫满足$P_i < P_{i+1}$，所以他们必须增加步数。 

任务是计算有多少种排列$[1..N]$对于给定的集合满足此约束$S$，跨多个测试用例，取模$10^9+7$。 

限制条件很大：$N$可以达到$2 \cdot 10^5$最多有$10^3$测试用例总计$K$全球范围内。 这立即排除了任何尝试枚举排列甚至模拟每个排列的约束的解决方案。 该结构必须简化为每个测试用例的组合公式，理想情况下是线性或接近线性的$K$。 

一个关键的微妙之处在于，这种情况是局部的，但会产生全球性的后果。 单个允许的下降位置会改变值的划分方式，因此单独处理位置会失败。 

一个天真的错误是认为每个索引$S$独立决定是否是血统。 这会建议一个简单的$2^K$-风格计数或阶乘分割，但这忽略了下降定义将排列分段为递增游程，并且这些游程必须是全局一致的。 

## 方法

 蛮力方法很简单：生成所有$N!$排列并检查每个下降位置是否位于$S$。 对于每个排列，我们扫描一次以识别所有索引$i$在哪里$P_i > P_{i+1}$，并验证哈希集中的成员资格。 这需要花费$O(N \cdot N!)$，即使对于$N = 10$。 

关键的观察是停止直接思考排列，而是关注由下降引起的结构。 每个排列都可以分解为最大递增段。 下降到某个位置$i$正是一个片段结束和下一个片段开始的地方。 

该约束规定段中断仅允许在以下位置$S$。 这意味着补$S$必须不包含中断，因此这些位置会强制增加运行中的连续性。 换句话说，我们将数组划分为递增的块，并且允许的分割点恰好是$S$。 

现在问题变成了：我们有多少种分配数字的方式$1..N$分成由强制非中断位置和可选中断位置确定的块，同时保留每个块内递增的顺序。 

应用标准转换：从左到右扫描并识别禁止中断的连续段。 这些强制约束将位置合并为组件。 合并后，每个组件都表现为单个“槽”，其中元素必须增加，但组件之间的相对顺序可以自由变化。 这将问题转化为计算块的排列（这是块数量的阶乘），以及乘以固定的内部排列。 

最终结构简化为根据强制邻接边下存在多少个连通分量来计算阶乘。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(N \cdot N!)$|$O(N)$| 太慢了|
 | 分量+阶乘计数 |$O(N)$每次测试 |$O(N)$| 已接受 |

 ## 算法演练

 我们将约束重新解释为强制邻接关系。 如果位置$i$不在$S$，那么我们必须有$P_i < P_{i+1}$，这意味着$i$和$i+1$必须位于同一个递增块中。 所以所有指数$i \notin S$强制建立连接$i$和$i+1$。 

1. 分类或存储$S$在哈希集中$O(1)$会员资格检查。 这使我们能够快速确定边界是允许还是禁止。 
2. 遍历索引$1$到$N-1$。 每当$i \notin S$，我们合并$i$和$i+1$到同一个组件中。 这会构建不允许下降的连续位置段。 
3. 计算产生了多少个连通分量。 如果我们从$N$孤立的位置并在强制时合并相邻的位置，每次合并都会减少一个组件的数量。 
4. 设组件数量为$C$。 关键的组合解释是每个组件的行为就像组件排列中的单个元素。 
5. 在每个组件内部，值必须严格递增，因此一旦将一组数字分配给一个组件，就只有一种排列它们的方式。 
6. 因此，唯一的自由就是改变$C$组件本身，贡献一个因素$C!$。 
7. 计算阶乘高达$N$一次，并输出$C!$对于每个测试用例。 

这样做的原因是强制非下降完全确定了内部排序约束。 每个强制增加边形成的连通分量都有固定的内部结构，内部不保留任何额外的自由度。 所有的可变性都来自于块相对于彼此的排序方式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    T = int(input())
    max_n = 2 * 10**5 + 5

    fact = [1] * (max_n)
    for i in range(1, max_n):
        fact[i] = fact[i - 1] * i % MOD

    for _ in range(T):
        n, k = map(int, input().split())
        s = set(map(int, input().split()))

        components = 1
        for i in range(1, n):
            if i in s:
                components += 1

        print(fact[components])

if __name__ == "__main__":
    solve()
```该解决方案预先计算阶乘一次，以便每个查询减少到计算形成的段数。 唯一重要的步骤是解释$S$: 中的每个索引$S$强制立场之间的分裂$i$和$i+1$，增加独立组件的数量。 

一个常见的实施错误是颠倒逻辑并合并$i \in S$。 这会错误地将允许的下降视为强制结构，而实际的强制约束来自外部位置$S$。 

## 工作示例

 考虑一个小案例，其中$N = 5$和$S = \{2, 4\}$。 这意味着仅位置 2 和 4 允许下降，因此位置 1 和 3 必须是递增边界。 

| 我| 在 S | 行动| 组件|
 | --- | --- | --- | --- |
 | 1 | 没有| 合并 (1,2) | 1 |
 | 2 | 是的 | 允许拆分 | 2 |
 | 3 | 没有| 合并 (3,4) | 2 |
 | 4 | 是的 | 允许拆分 | 3 |

 我们以 3 个组件结束，所以答案是$3! = 6$。 这显示了禁止位置如何破坏结构。 

现在考虑$N = 4$,$S = \{1,2,3\}$。 每个位置都允许下降，因此不存在强制合并。 

| 我| 在 S | 组件|
 | --- | --- | --- |
 | 1 | 是的 | 1 |
 | 2 | 是的 | 2 |
 | 3 | 是的 | 3 |
 | | | 共 4 条 |

 我们得到$4$组件，所以答案是$4! = 24$，这意味着所有排列都是有效的，因为没有位置被限制为增加。 

这些例子表明，约束只会在强制邻接时减少自由度，而不会在仅仅允许下降时减少自由度。

## 测试用例```python
import sys, io

MOD = 10**9 + 7

def solve():
    input = sys.stdin.readline
    T = int(input())
    max_n = 2 * 10**5 + 5
    fact = [1] * max_n
    for i in range(1, max_n):
        fact[i] = fact[i - 1] * i % MOD

    out = []
    for _ in range(T):
        n, k = map(int, input().split())
        s = set(map(int, input().split()))
        comp = 1
        for i in range(1, n):
            if i in s:
                comp += 1
        out.append(str(fact[comp]))
    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

 ## 边缘情况

 一个微妙的情况是当$S$是空的。 这迫使每个位置$i$满足$P_i < P_{i+1}$，因此排列必须是严格递增的。 只有一种排列满足这一点，并且该算法恰好产生一个分量，给出$1! = 1$，符合预期结果。 

另一个角落是当$S$包含来自的所有索引$1$到$N-1$。 那么就不会强制邻接，因此每个排列都是有效的。 算法算数$N$组件，生产$N!$，它与完整的排列空间对齐。 

第三种情况是分散的约束，例如交替成员资格。 每个缺失的索引都会合并两个位置，因此组件在不存在约束的情况下精确收缩。 跟踪合并过程证实，每个强制相等都会将自由度减少恰好一个邻接，从而保留组件对应于最大强制增加段的不变性。
