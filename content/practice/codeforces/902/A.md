 ## 解决方案
 ## 问题理解

 我们有一组沿着一维数轴放置的传送器。 Pig 从位置 0 开始，想要到达位置 m。 每个传送器位于某个坐标ai，如果Pig到达该坐标，他可以选择从ai到bi区间内的任何目的地。 

传送按顺序呈现，当我们向下移动列表时，它们的起始位置永远不会减少。 这种顺序很重要，因为它允许我们从左到右处理它们，而无需重新考虑早期的结构。 

任务是确定是否存在从 0 开始并最终到达 m 的传送使用序列。 

限制很小。 最多 100 次传送，即使是 O(n²) 模拟也能轻松通过，但结构表明更简单的线性扫描就足够了。 关键的困难不是计算时间，而是理解随着新的传送变得可用，可达性如何演变。 

一个幼稚的误解通常来自于独立对待每个传送。 例如，假设能够立即到达 ai 处的传送意味着您必须使用它，或者假设您只能按照严格的使用顺序而不是可用性来使用传送。 另一个微妙的错误是忽略了传送可能会超出其自身位置，从而使以后的传送变得可用。 

具体的失败案例如下所示：

 输入：```
2 5
0 1
2 5
```粗心的方法可能会尝试严格链接，但没有意识到仅达到 1 不允许访问 2 处的第二个传送点，因此答案是否定的。 但正确的到达跟踪方法会发现第一个传送上限达到 1，这是不够的，因此进度会停止。 

另一个边缘情况：

 输入：```
2 5
0 3
1 2
```尽管第二次传送在实用性上似乎“倒退”了，但如果我们已经比第一次传送得更远了，那就无关紧要了。 正确的逻辑必须始终优先选择最大可达扩展，而不是最近遇到的传送。 

## 方法

 蛮力的想法是将其视为可达性问题，从当前位置开始，我们尝试每个可用的传送，在允许的时间间隔内递归地探索所有可能的目的地。 这有效地构建了一个图表，其中每个间隔中的每个点都是一个节点，并且传送创建了密集的有向连接。 虽然在概念上是正确的，但这种情况会爆炸，因为每次传送都可以生成连续的可达点，即使离散化，我们也可能会反复重新访问状态。 在最坏的情况下，探索传送使用的所有组合会导致指数行为。 

关键的观察是，我们永远不需要跟踪所有可到达的位置，只需要跟踪 Pig 当前可以到达的最远点。 如果我们可以到达ai，那么该传送的最佳用途就是将到达范围扩展到bi。 由于所有运动在位置方面都是单调的（我们永远不需要向后退），因此问题简化为贪婪地扩展边界。 

我们按照人工智能的递增顺序处理传送。 每当传送的起点在我们当前的可达范围内时，我们就可以使用它来扩展该范围。 如果传送开始超出我们当前可以到达的范围，我们还无法使用它，并且由于未来的传送从更右侧开始（由于顺序），因此当我们遇到这样的差距时，我们将停止检查进一步的扩展。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（状态搜索）| 指数| 高| 太慢了 |
 | 贪婪范围扩张 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们维护一个代表 Pig 当前可以到达的最远位置的值。 

1. 将可达位置初始化为 0，因为 Pig 从那里开始。 
2. 按给定顺序迭代每个传送。 
3. 如果瞬移的起始点ai大于当前可到达的位置，则停止处理进一步的瞬移。 这是有效的，因为后来的传送从更右侧开始，因此也无法到达。 
4. 如果ai在可达范围内，则将可达位置更新为max(currentreach,bi)。 这反映了最佳地使用传送来尽可能向右延伸。 
5. 处理完所有可用的传送后，检查可到达的位置是否至少为 m。 如果是，Pig可以联系到该朋友； 否则他不能。 

### 为什么它有效

 在每一步中，算法都保持不变式，即可到达位置是 Pig 使用已处理前缀的任何传送序列可以到达的最大最右边点。 因为传送是按ai排序的，一旦遇到起始点超出当前范围的传送，以后的传送就永远无法激活。 在所有可用的传送中，贪婪地获取 bi 是最佳的，因为 [ai, bi] 内的任何中间选择只能减少或等于未来的到达范围，而永远不会提高它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    reach = 0
    
    for _ in range(n):
        a, b = map(int, input().split())
        
        if a > reach:
            break
        
        if a <= reach:
            if b > reach:
                reach = b
    
    print("YES" if reach >= m else "NO")

if __name__ == "__main__":
    solve()
```其实现直接反映了贪婪的想法。 变量`reach`存储迄今为止可到达的最远位置。 早期的休息很重要：一旦传送无法到达，后面的传送就无法提供帮助，因为排序人工智能。 最大更新确保我们始终尽可能扩大覆盖范围。 

一个常见的错误是删除中断并继续扫描，这仍然是正确的，但在较大的变体中速度较慢。 另一个错误是用ai而不是bi更新reach，这会忽略每个传送的扩展能力。

 ## 边缘情况

 一个边缘情况是第一个传送不从 0 开始。例如，如果第一个 ai 为 1，Pig 根本无法移动，所以答案立即为“否”。 该算法自然地处理这个问题，因为reach从0开始，并且第一次检查>reach导致终止。 

另一种情况是多个传送严重重叠时。 即使稍后的传送间隔更小，也没关系，因为到达范围只能通过最大更新来增长。 该算法安全地忽略无用的回归，因为它永远不会减少覆盖范围。
