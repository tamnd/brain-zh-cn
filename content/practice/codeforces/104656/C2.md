 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并要求将其精确地分解为$k$连续的段。 每个元素必须恰好属于一个段，并且任何段都不能为空。 一旦数组被分割，每个段都会产生一个分数，定义为其元素减模后的总和$p$。 我们想要的最终值是这些分段分数的总和，并且我们必须选择使该总分数最大化的分区。 

重新表述目标的一个有用方法是我们正在选择$k-1$切割位置，每个结果块贡献其总和模一个小数$p \le 100$。 每个段内模数的存在使问题变得非线性，因为分割段不仅会改变元素的分组方式，还会改变余数的行为方式。 

这些约束意味着特定的算法形状。 数组长度可达 20,000，而$k$最多 50。尝试所有分区的简单方法是指数级的$k$或者至少是二次方$n$每层DP，速度太慢。 然而，较小的值$k$强烈建议采用动态编程解决方案，其中对每层的转换进行优化，而不是从头开始重新计算所有内容。 

一些边缘情况值得尽早隔离。 如果$k = 1$，没有分区，所以答案只是整个数组模的总和$p$。 天真的 DP 可能仍然会尝试分裂并意外地引入无效的转换。 另一个微妙的情况出现时$k = n$，这意味着每个元素都必须是它自己的段。 那么答案就变成了$a_i \bmod p$，并且任何依赖于较长段的解决方案仍必须正确处理单元素段。 最后，具有大值的数组可能会误导重复重新计算总和的实现，因为 DP 转换内的重新计算成为瓶颈。 

## 方法

 蛮力的观点很简单：选择$k-1$之间的分割点$n-1$位置，评估每个分区，计算段总和，减少每个模$p$，并跟踪最大值。 这是正确的，因为它探索了每个有效的细分。 问题是选择分割点的方法数量是$\binom{n-1}{k-1}$，即使对于中等强度的情况来说，它也会变得天文数字般大$n$。 即使我们评估每个分区$O(n)$，这种方法立即崩溃。 

关键的观察是，如果我们确定采用的段数以及最后一段的结束位置，则存在最佳子结构。 如果我们已经知道将前缀划分到位置的最佳方法$i$进入$t-1$段，然后延伸至$i+1$为了$t$片段仅取决于最后一次切割的放置位置。 这将问题转化为分层DP，其中每个状态代表“首先使用的最佳值”$i$元素和$t$段”。

 困难在于转换需要计算段和模$p$高效。 自从$p \le 100$，我们可以维护前缀和模$p$并用它们来计算任何细分市场的贡献$O(1)$。 这使得每个 DP 转换独立于段长度。 

主要的优化是减少从$O(n)$每个州$O(p)$或者$O(1)$-通过跟踪每个可能的前缀模类的最佳值来摊销。 我们不是扫描每个状态的所有先前剪切位置，而是维护按前缀位置分组的最佳可实现 DP 值并重复使用它们。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（所有分区）|$O(\binom{n}{k} \cdot n)$|$O(n)$| 太慢了|
 | 带前缀重新计算的 DP |$O(k n^2)$|$O(nk)$| 太慢了|
 | 使用前缀 mod 状态优化 DP |$O(k n p)$|$O(nk)$| 已接受 |

 ## 算法演练

 我们定义一个 DP 表，其中$dp[t][i]$是我们通过拆分前缀可以获得的最大总分$A[1..i]$准确地进入$t$段。 

1. 预先计算模前缀和$p$。 让$pref[i]$是$(A_1 + \dots + A_i) \bmod p$。 这允许恒定时间段查询。 
2. 初始化一个段的基本情况。 对于每一个$i$,$dp[1][i]$简直就是$pref[i]$，因为整个前缀被视为一个段，其分数是其模数之和$p$。 
3. 对于每个段数$t$从 2 到$k$, 计算$dp[t][i]$通过考虑最后一段的开始位置。 如果最后一段从位置开始$j+1$，则最后一段得分为$(sum(j+1..i) \bmod p)$，等于$(pref[i] - pref[j]) \bmod p$。 
4. 将转换重写为$$dp[t][i] = \max_{j < i} (dp[t-1][j] + (pref[i] - pref[j]) \bmod p).$$对两者的依赖$dp[t-1][j]$和$pref[j]$建议按残基类别对状态进行分组$pref[j]$。 
5. 对于固定$t$, 迭代$i$从左到右，同时保持一个跟踪最佳值的辅助结构$dp[t-1][j] - pref[j]$对于每个残留类别。 自从$p$很小，我们存储每个可能的最佳值$pref[j]$模数$p$，随着我们的进展进行更新。 
6. 使用这些保持的最佳值来计算每个$dp[t][i]$在常数时间内，因为对于任何$i$，表达式简化为选择最佳兼容的先前残基。 
7. 填充所有层后$k$，答案是$dp[k][n]$。 

正确性依赖于每个段贡献仅取决于前缀差异模的事实$p$，这些差异完全由前缀残基决定。 这将对所有先前剪切位置的搜索折叠成由残基索引的有界状态集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, p = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = (pref[i - 1] + a[i - 1]) % p

    dp_prev = [-10**18] * (n + 1)
    dp_prev[0] = 0

    for t in range(1, k + 1):
        dp = [-10**18] * (n + 1)

        best = [-10**18] * p

        for i in range(1, n + 1):
            j = i - 1

            val = dp_prev[j] - pref[j]
            r = pref[j]
            if val > best[r]:
                best[r] = val

            cur = pref[i]
            dp[i] = best[cur] + pref[i]

        dp_prev = dp

    print(dp_prev[n])

if __name__ == "__main__":
    solve()
```该实现仅保留两个 DP 层，因为每个状态仅依赖于前一个状态。 数组`best[r]`存储最佳可实现的值$dp[t-1][j] - pref[j]$所有职位中$j$其前缀和模$p$等于$r$。 这正是允许过渡避免扫描所有先前剪切点的原因。 

一个常见的错误是更新`best`计算后`dp[i]`。 顺序很重要：处理位置时`i`，我们必须首先合并索引`i-1`在将其用于转换之前先进入该结构，否则我们会丢失恰好结束于的有效分区`i-1`。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(k \cdot n \cdot p)$| 对于每个$k$层，我们扫描一次数组并维护$p$残留状态|
 | 空间|$O(n + p)$| 前缀数组加上两个DP层和一个小的残差表|

 界限$n \le 20000$,$k \le 50$， 和$p \le 100$使这种方法安全。 总运营量约为$10^8$在最坏的情况下，但常数因子很小，因为更新是简单的数组访问。

## Edge Cases

A critical edge case is when \(k = 1\). The algorithm collapses to a single DP layer where no transition is performed, and the answer is directly the prefix sum modulo \(p\). The DP initialization already handles this because \(dp[1][n]\) equals the full prefix modulo value.

Another case is when all elements are identical. Here many partitions produce similar segment sums, and a greedy-looking update of `best` can accidentally overwrite optimal states if updates are not ordered carefully. The algorithm avoids this by processing indices in increasing order and only extending from previously finalized prefix positions.

A final subtle case arises when prefix sums wrap around modulo \(p\). Two different prefix indices may share the same residue, and a naive DP that ignores grouping by residue would incorrectly treat them as distinct. The `best[r]` array resolves this by collapsing all such states into a single optimal representative per residue class, ensuring no valid transition is lost.
