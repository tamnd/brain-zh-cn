 ## 解决方案
 ## 问题理解

 我们从一个数字开始，重复应用一个非常具体的转换：找到大于 1 的最小除数，并将该值添加到该数字中。 此操作会更改数字本身，因此我们使用的除数可能会在每一步发生变化。 完全这样做之后`k`有时，我们会被要求提供最终值。 

关键对象是函数`f(n)`，这只是最小的质因数`n`。 如果`n`是素数，`f(n) = n`。 如果`n`是复合的，`f(n)`是除它的最小素数。 

每一次行动都让我们从`n`到`n + f(n)`。 自从`k`可以大到$10^9$，我们无法一步步模拟。 然而，所有的总和`n`测试用例最多是$10^6$，这暗示我们需要对达到该范围的数字进行预处理并有效地重用它。 

一种简单的方法是模拟每个查询的每个步骤。 在类似的情况下，这会立即失败`n = 10^6, k = 10^9`，即使是单个测试用例也需要数十亿次转换。 

当出现微妙的边缘情况时`n`是质数或在此过程中变成质数。 例如，从像这样的素数开始`3`，我们得到：`3 → 6 → 8 → 10 → 12 ...`这里的行为很快稳定下来，因为一旦数字变成偶数，最小的除数就会保持不变`2`永远。 每次尝试从头开始重新计算除数的粗心实现将会超时。 

## 方法

 蛮力的想法很简单：对于每一步，通过扫描重新计算当前数字的最小除数`2`向上，然后添加并重复。 这是正确的，因为它直接遵循定义。 问题是找到除数可能需要长达$O(\sqrt{n})$，并执行此操作直到$k$每个查询导致的次数$O(k \sqrt{n})$，当`k`达到$10^9$。 

关键的观察结果是该过程具有很强的稳定行为。 唯一一次的价值`f(n)`不是`2`是什么时候`n`很奇怪。 一旦我们加上奇数个最小质因数，结果就变成偶数。 从那时起，每个数字都保持偶数，所以`f(n)`总是`2`。 

这意味着该过程对于每个奇数最多有一次“昂贵”的转换：我们从奇数状态跳转到偶数状态，之后序列以恒定增量变为线性`2`。 因此，我们不是一步步模拟，而是只模拟直到`k`用完或者我们达到一个偶数，然后在一次算术跳跃中完成剩下的部分。 

我们预先计算所有数字的最小质因数$10^6$使用筛子。 然后，每个查询最多只需要几个步骤就可以贪婪地处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(k \sqrt{n})$|$O(1)$| 太慢了|
 | 最佳|$O(n \log \log n + t \cdot \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们首先预处理每个整数的最小质因数，直到最大可能的质因数`n`使用筛子。 

之后，每个查询都会被独立处理。 

1. 将当前值初始化为`x = n`并保留`k`剩余操作。 
2. 虽然`k > 0`和`x`是奇数，计算`f(x)`使用预先计算的数组并更新`x = x + f(x)`，然后递减`k`。 
3.一次`x`变得均匀（或者我们耗尽操作），我们停止逐步模拟。 
4. 如果仍有操作，我们添加`2 * k`到`x`并立即完成。 

步骤 4 背后的关键推理是，一旦一个数是偶数，它的最小除数总是`2`，所以每个剩余的操作都准确贡献`2`。 

### 为什么它有效

 该过程自然分为两个阶段。 在第一阶段，该值可能是奇数，最小除数取决于其因式分解。 每一个这样的步骤都会严格增加数量并经常翻转奇偶校验。 一旦数字变成偶数，它就永远留在偶数域，并且最小除数变得不变（`2`）。 这创建了一个单调系统，最多只有一次转变为稳定的线性状态，确保贪婪模拟既正确又有界。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXN = 10**6 + 5

spf = list(range(MAXN))

# sieve for smallest prime factor
for i in range(2, int(MAXN**0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXN, i):
            if spf[j] == j:
                spf[j] = i

def solve(n, k):
    x = n
    
    while k > 0:
        if x % 2 == 0:
            break
        x += spf[x]
        k -= 1
    
    if k > 0:
        x += 2 * k
    
    return x

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    print(solve(n, k))
```筛子建立最小的素因子表，使得每个`f(x)`查询时间复杂度为 O(1)。 模拟循环仅在数量为奇数时运行，确保每个测试用例最多进行几次迭代。 一旦我们达到偶数，我们就利用最小除数固定为 2 的不变量，允许我们在常数时间内跳转剩余的步骤。

 ## 边缘情况

 一个关键的边缘情况是数字开始为偶数时。 例如，`n = 2`。 最小的除数总是`2`，所以每个操作都精确地相加`2`。 该算法立即跳过模拟并应用直接乘法`k`，符合真实流程。 

另一种情况是当数字以大质数开始时。 为了`n = 999983`，第一步大约将其加倍，之后就变成偶数。 向稳定状态的转变发生在一次迭代中，循环在切换到线性公式之前捕获这一点。 

最后一个微妙的情况是`k = 0`。 不应进行任何操作，因此答案必须等于原始答案`n`。 这是自然处理的，因为循环和最终加法都依赖于`k > 0`。
