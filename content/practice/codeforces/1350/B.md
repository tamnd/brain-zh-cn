 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 在每个模型中，我们都有一系列从 1 到 n 索引的模型大小。 我们可以选择索引的子集，但所选索引必须保持递增顺序，这相当于选择索引的子序列。 

仅当每对连续的选定索引同时满足两个约束时，选定的子序列才有效。 首先，下一个索引必须是前一个索引的倍数。 其次，下一个索引的大小必须严格大于前一个索引的大小。 目标是最大化在这些规则下可以选择的指数数量。 

约束足够大，每个测试用例 n 可以达到 100,000，所有测试用例的总和也达到 100,000。 这立即排除了对所有指数对的任何二次方法。 检查所有对之间的转换或尝试显式构建子序列的解决方案将太慢。 每个测试用例我们需要更接近线性或 n log n 的东西。 

一个微妙的点是该结构不是索引上的一般子序列 DP。 可整性约束强制仅从 i 转换到它的倍数，这使得图稀疏且结构化。 忽略此结构会导致 O(n^2) DP 失败。 

经常破坏朴素解决方案的边缘情况包括所有值都相等的数组，例如 n = 5、s = [7, 7, 7, 7, 7]。 这里，不存在有效的转换，因为严格增加是不可能的，所以答案必须是 1。另一种边缘情况是当值严格增加但索引与整除结构不对齐时，例如 n = 5，s = [1, 2, 3, 4, 5]。 即使值增加，也只允许像 1 → 2 → 4 这样的乘法索引链，因此答案受到索引结构而不是值顺序的限制。 

## 方法

 直接的暴力策略将尝试计算以每个索引结尾的最长有效子序列。 对于每个索引 i，我们将检查所有先前的索引 j < i 并验证 j 是否整除 i 且 s[j] < s[i]。 如果两者都成立，我们更新 dp[i] = max(dp[i], dp[j] + 1)。 这是正确的，因为它直接遵循有效链的定义。 

然而，这种方法对每个 i 最多检查 i 个先前元素，在最坏的情况下导致大约 n(n−1)/2 个转换。 当 n = 100,000 时，这远远超出了可行的限制。 

关键的观察是转变不是任意的。 对于任何索引 i，我们只需要考虑它的倍数 i、2i、3i 等。 这翻转了思维方向：我们不是检查 i 的所有先前状态，而是沿着倍数向前传播 dp 值。 这是有效的，因为所有 i 的倍数数量以 n log n 为界。 

我们计算 dp[i] 作为以 i 结尾的最佳链。 然后，对于每个 i，我们尝试将其扩展到所有倍数 j = 2i, 3i, ...，如果 s[j] 大于 s[i]，则更新 dp[j]。 这将问题转换为可分图上的结构化 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有对进行暴力 DP | O(n^2) | O(n^2) | O(n) | 太慢了|
 | DP 倍数（整除性传播）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 ### ## 算法演练

 1. 初始化一个 dp 数组，其中 dp[i] 表示以索引 i 结束的有效链的最大长度。 对于所有 i，从 dp[i] = 1 开始，因为每个元素单独形成一个有效的链。 
2. 按升序从 1 迭代到 n。 对于每个 i，我们将其视为向前延伸链的起点。 
3. 对于每个 i，迭代其倍数 j = 2i、3i、4i，直到 n。 对于每个这样的 j，检查 s[j] 是否严格大于 s[i]。 如果是，则更新 dp[j] = max(dp[j], dp[i] + 1)。

此步骤之所以有效，是因为任何有效的转换都必须满足索引整除条件，因此 i 的所有可能的后继者都恰好是它的倍数。 
4. 不断传播改进措施。 由于我们按升序处理 i，因此在从 i 扩展时已经考虑了较小索引的所有贡献。 
5. 处理完所有索引后，答案就是 dp 中的最大值。 

### 为什么它有效

 dp 状态捕获在仅沿有效整除边缘发生转换的约束下以每个索引结束的最长有效链。 每个有效序列都可以分解为连续的步骤，其中每个下一个索引是前一个索引的倍数，因此在处理较小端点时，每个转换都被考虑一次。 因为我们仅在 s[j] 严格较大时更新 dp[j]，所以我们保留了值所需的单调性。 不会错过任何有效的扩展，因为 j 的每个有效前驱都必须是 j 的除数，因此在迭代顺序中会先处理。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = [0] + list(map(int, input().split()))

        dp = [1] * (n + 1)
        ans = 1

        for i in range(1, n + 1):
            val = dp[i]
            if val > ans:
                ans = val

            j = 2 * i
            while j <= n:
                if s[j] > s[i]:
                    if dp[j] < val + 1:
                        dp[j] = val + 1
                j += i

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案构建了一个 dp 数组，其中每个位置都以长度为 1 的链开始。 倍数上的嵌套循环确保每个有效的转换 i → j（其中 j 可被 i 整除）被仅考虑一次。 比较 s[j] > s[i] 强制执行严格增加大小条件。 

一个微妙的实现细节是，我们在迭代多个之前将 dp[i] 存储在局部变量中。 这可以防止重复的数组查找并确保传播的清晰度。 另一个重要的一点是使用基于 1 的索引，它直接与问题陈述对齐，并避免生成倍数时出现差一错误。

 ## 边缘情况

 具有单个元素的最小输入立即返回 1，因为不可能进行转换。 该算法自然地处理这个问题，因为 dp 被初始化为 1，并且倍数上的循环不会产生更新。 

当所有值都相等时，例如 s = [7, 7, 7, 7]，每次比较 s[j] > s[i] 都会失败，因此对于所有索引，dp 保持为 1 不变。 因此最终的最大值为 1，与正确的输出相匹配。 

当值增加但索引与乘法结构不能很好地对齐时，例如 s = [1, 2, 3, 4, 5, 6]，则只有遵循索引整除性的链（例如 1 → 2 → 4 或 1 → 3 → 6）是可能的。 该算法正确地遵循了这一点，因为它仅沿倍数传播，而从不在任意索引之间传播。
