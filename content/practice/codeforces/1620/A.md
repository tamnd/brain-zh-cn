 ## 解决方案
 ## 问题理解

 给定一个正整数的圆形数组，对于圆中的每个相邻对，我们知道这些数字是否相等。 输入以字符串形式提供此信息`s`字符数`E`和`N`， 在哪里`E`表示两个邻居必须相等并且`N`表明它们一定是不同的。 挑战在于决定是否可以将满足所有这些等式和不等式的实际数字分配给数组。 我们不需要构造数组，只需对每个测试用例回答“是”或“否”即可。 

限制很小：数组长度`n`范围从 2 到 50，最多可以有 1000 个测试用例。 自从`n`很小，检查所有对或每个测试用例执行多次线性传递的算法是可以接受的。 核心困难是推理循环结构中的等式链，其中`E`约束传播到多个元素，并且`N`如果约束与这些链相矛盾，就会产生冲突。 

当所有关系都存在时，就会出现一个重要的边缘情况`N`。 例如，对于`n = 3`和`s = NNN`，每个元素必须与其邻居不同。 这是不可能的，因为圆闭合，一个元素必须等于另一个元素才能满足最后一个元素`N`。 粗心的实现可能会忽略循环闭包并错误地输出 YES。 当只有一个时，会发生另一种微妙的情况`N`包围着`E`s: 的`E`链可以吸收元素，但单个`N`边界可能会产生不可避免的冲突。 

## 方法

 暴力方法是尝试所有可能的数字分配，直到某个大范围（例如 10^9）。 对于每个作业，我们检查是否每个`E`比赛和每`N`不同。 这是正确的但不切实际：对于`n = 50`，即使每个元素尝试 2 个值也需要 2^50 次赋值，远远超出了可行的计算范围。 

最优方法将问题视为两个可能值的建设性分配。 我们可以为每个元素分配一个标签，沿圆周传播等式约束。 如果两个元素通过以下方式连接`E`，它们必须共享相同的标签。 如果通过连接`N`，它们一定不同。 关键的见解是我们只需要两个不同的标签，因为每个`N`约束仅要求两个端点不同。 如果字符串`s`完全由`E`s，我们可以为所有元素分配相同的值。 否则，任何安排`N`只要有至少一个就可以解决`N`并且链条可以从该点开始。 唯一不可能的情况是当`n = 3`所有三个约束都是`N`或其他模式，其中每个元素必须与大小为 3 的圆中的每个元素都不同。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 太慢了 |
 | 建设性的双标签 | 每个测试用例 O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`并迭代每个测试用例。 每个测试用例提供一个字符串`s`长度`n`。 
2.如果`s`仅包含`E`s，立即打印YES。 这是有效的，因为我们可以为圆中的所有元素分配相同的数字。 
3. 对于其他字符串，我们检查特殊不可能情况：`n = 3`所有字符都是`N`。 在这种情况下，每个元素必须与其相邻元素不同，这在长度为 3 的圆中是不可能的。 
4. 在所有其他情况下，我们可以通过从第一个数字开始交替分配两个不同的数字来构造有效的分配`N`约束。 如果邻居必须相等，则传播相同的标签； 如果邻居必须不同，则交换标签。 
5. 由于我们只需要确定可行性，而不需要显式构造数组，因此如果避免了不可能的 3 元素全 N 情况，我们可以得出 YES 的结论。 
6. 对于不可能的情况打印“NO”，否则打印“YES”。 

工作原理：通过将等式视为连通分量，将差视为分量之间的约束，我们可以看到任何长度大于 3 且至少有一个等式或差的字符串都可以用两个不同的数字来满足。 平等的传播确保了`E`是一致的，差异可以通过两个标签之间的翻转来满足。 该算法永远不会产生假“是”，因为它显式处理 3 元素循环全 N 冲突。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)
        if s.count('E') == n:
            print("YES")
        elif n == 3 and s == "NNN":
            print("NO")
        else:
            print("YES")

if __name__ == "__main__":
    solve()
```第一部分读取输入并迭代测试用例。 检查`s.count('E') == n`有效地处理所有平等的情况。 专项检查`n == 3 and s == "NNN"`捕捉最小圆中唯一不可能的排列，其中每个邻居都必须不同。 所有其他安排都自动可行，因此我们打印 YES。 边界处理是自动的，因为字符串长度是直接从输入中使用的，并且循环闭包仅与我们显式检查的不可能模式相关。

 ## 边缘情况

 用于输入`NNN`，算法检查`n == 3 and s == "NNN"`并打印 NO，正确处理不可能的情况。 对于长度为 50 且所有的字符串`E`即，计数检查触发并打印 YES。 对于交替`N`和`E`，算法打印 YES，因为 50 个元素的圆可以满足交替分配的两个数字，从而确认传播不变式成立。 所有边界情况`n = 2`处理起来很简单，因为任何配置`E`或者`N`是可行的。
