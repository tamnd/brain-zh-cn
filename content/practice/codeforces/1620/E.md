 ## 解决方案
 ## 问题理解

 我们从一个空序列开始，处理一系列操作，这些操作要么在末尾附加一个值，要么全局地将每个出现的一个值重命名为另一个值。 最终任务是在应用所有操作后输出结果序列。 

关键的困难在于替换操作是全局性的且重复的，因此早期出现的值可能会在以后多次受到影响。 幼稚的解释会在每次替换时重复扫描并重写整个数组，这与输入大小不兼容。 高达$5 \cdot 10^5$操作中，每次更新的完全遍历会导致二次行为，这远远超出了 2 秒可以处理的范围。 

输出大小恰好是追加操作的数量，因此最多$5 \cdot 10^5$必须打印元素。 这已经迫使任何解决方案总体上接近线性或线性算数。 

对于简单的方法来说，一些微妙的失败案例会立即出现。 如果我们逐字存储数组，并在类型 2 的每个查询上扫描并替换所有匹配元素，最坏的情况是长交替替换序列，例如用 2 替换 1，然后用 3 替换 2，然后用 4 替换 3，重复应用于大型数组。 即使每次替换只涉及数组的一小部分，累积成本也会成二次方。 

另一个陷阱是仅更新新附加的元素以进行替换，而忘记了较早出现的元素也必须更改。 例如，构建后`[1, 1, 1]`, 一个查询`2 1 2`必须将整个数组转换为`[2, 2, 2]`，而不仅仅是未来的插入。 

真正的问题是值的行为就像可变的身份而不是固定的整数，我们需要一种方法来表示“值的当前含义”，而无需每次都重写整个结构。 

## 方法

 蛮力方法很简单。 显式维护数组。 对于类型 1 的查询，附加值。 对于类型 2 的查询，迭代整个数组并替换每次出现的`x`和`y`。 这是正确的，因为它直接模拟了问题定义。 然而，每次更换都会花费$O(n)$，并且可以有$O(q)$这样的操作，产生$O(q^2)$最坏情况下的行为。 和$q = 5 \cdot 10^5$，这是不可行的。 

关键的观察是，存储在数组中的实际数值并不重要，重要的是所有替换后其当前的“代表”。 如果我们能够快速确定一个值在一系列替换后变成了什么，我们就可以避免触及数组。 

这建议维护从每个值到其当前代表的映射。 然而，替换并不是独立的任务； 可以形成链，例如`1 → 2`， 然后`2 → 3`，这意味着之前映射到 1 的所有内容现在也必须遵循 3。此结构自然由不相交集并集样式父指针系统处理，其中每个值都指向其当前代表。 替换操作成为整个代表节点的重定向。 

为了确保正确性，每个附加值都以其原始形式存储，并且在输出期间，我们通过重复父级跳转到其最终代表来解析它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(q^2)$|$O(q)$| 太慢了 |
 | DSU 式映射 |$O(q \alpha(q))$|$O(q)$| 已接受 |

 ## 算法演练

 我们将每个值建模为属于代表其当前活动身份的父指针结构。 

1. 初始化一个父数组，使每个值都是其自己的父数组。 这表示最初没有发生替换。 
2. 维护清单`ans`它存储与类型 1 查询期间附加的值完全相同的值，而不尝试立即解释替换。 这种分离可以防止重复重写。 
3. 对于类型的查询`1 x`, 追加`x`到`ans`。 这存储了插入的历史身份。 
4. 对于类型的查询`2 x y`，我们重定向代表`x`致代表`y`。 具体来说，我们找到当前的根`x`并将其附加到根`y`。 这确保了之前等于的所有值`x`现在变得相当于`y`。 
5. 处理完所有查询后，我们通过使用路径压缩将每个存储值替换为其根代表来计算最终数组。 

微妙的一点是我们从不修改早期的条目`ans`。 相反，我们最后通过并查找结构重新解释它们。 

### 为什么它有效

 插入数组中的每个值都带有当时数字版本的标识。 替换查询永远不需要重新访问这些存储的条目，因为它们只会影响身份今后如何相互映射。 并查结构保证，如果两个值通过一系列替换变得相等，则它们共享相同的代表根。 路径压缩可确保解析任何值在接近恒定的时间内产生其最终形式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

MAXV = 500000 + 5
parent = list(range(MAXV))

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

q = int(input())
ans = []

for _ in range(q):
    tmp = input().split()
    if tmp[0] == '1':
        x = int(tmp[1])
        ans.append(x)
    else:
        x = int(tmp[1])
        y = int(tmp[2])
        px = find(x)
        py = find(y)
        if px != py:
            parent[px] = py

out = []
for v in ans:
    out.append(str(find(v)))

print(' '.join(out))
```该实现将存储与转换分开。 这`ans`列表保留插入顺序，而 DSU 结构跟踪值的等价类。 

这`find`函数使用路径压缩，这确保对相同值的重复查询变成恒定的摊销时间。 类型 2 中的联合操作始终链接根，这可以防止错误的部分合并。 

一个微妙的细节是我们只联合根，而不是原始值。 没有这个，链就像`1 → 2 → 3`不会正确崩溃。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(q \alpha(V))$| 每个查询最多执行一到两个查找操作，由于路径压缩，摊销成本接近恒定 |
 | 空间|$O(V + q)$| DSU 父数组加上附加元素的存储 |

 约束允许最多$5 \cdot 10^5$操作，并且该解决方案有效地线性运行，很容易在限制范围内拟合。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MAXV = 500000 + 5
    parent = list(range(MAXV))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    q = int(input())
    ans = []

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            ans.append(int(tmp[1]))
        else:
            x, y = int(tmp[1]), int(tmp[2])
            px, py = find(x), find(y)
            if px != py:
                parent[px] = py

    return " ".join(str(find(v)) for v in ans)

 ## 边缘情况

 一种边缘情况是重复自我更换，例如`2 x x`。 在这种情况下，代表`x`已经与自身相同，因此联合操作不应该执行任何操作。 该算法处理这个问题是因为`find(x)`等于`find(x)`并且不会发生父级更新。 

另一种情况是长替换链，例如`1→2→3→4`。 DSU 结构在查询或输出遍历期间压缩该链，确保解析任何中间值直接返回最终代表，而无需重新访问整个链。 

第三种情况是经常插入的值的延迟替换。 由于所有出现的情况都存储一次并仅在最后解决，因此成本不取决于值在数组中出现的频率，而仅取决于存在的操作数量。
