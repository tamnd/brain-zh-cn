 ## 解决方案
 ## 问题理解

 我们得到一系列索引从 1 到 n 的植物，所有植物最初的含水量都为零。 每个查询指定一个段$[l, r]$，并且对于每个位置$i$在该部分中，我们添加一个值，该值取决于距离$i$来自$l$。 如果我们定义$x = i - l + 1$，那么在位置上的贡献$i$是$f(x)$， 在哪里$f(x)$等于$x$乘以其最低有效设置位的值。 

最低有效设置位是除以 2 的最大幂$x$。 所以如果$x = 12 = 1100_2$，值为$4$， 和$f(12) = 12 \cdot 4 = 48$。 因此，每个查询都会在其间隔内注入结构化模式，从 1 开始$l$，然后按照顺序$f(1), f(2), f(3), \dots$。 

输出是处理所有查询后每个工厂的最终累积水量。 

约束很严格：两者总计$n$所有测试用例的查询总数受以下限制$2 \cdot 10^5$。 这排除了通过迭代其整个范围并直接更新每个元素来处理每个查询的任何方法，因为在最坏的情况下这将是二次的。 

一个简单的模拟确实$O(r-l+1)$每个查询的工作量，导致$O(nq)$全面的。 和$n, q$最多$2 \cdot 10^5$，那将是大约$4 \cdot 10^{10}$的操作，远远超出了可行的限度。 

重叠模式会产生微妙的边缘情况。 每个查询都会贡献一个高度非线性的序列，因此任何预先计算前缀和的尝试$f(x)$除非我们了解如何跨段重用结构，否则单独使用并不能立即有所帮助。 

## 方法

 暴力法很简单。 对于每个查询$[l, r]$，我们循环遍历所有位置$i$并计算$x = i - l + 1$，然后添加$f(x)$到答案。 这是正确的，因为它直接遵循定义，但是当所有查询长度之和很大时，它太慢了。 

关键的观察结果是，尽管查询作用于数组的不同段，但所应用的函数始终是从 1 开始的相同序列。$f(x)$仅取决于$x$，而不是绝对位置。 这意味着每个查询相当于添加固定无限数组的移位副本$A[x] = f(x)$。 

困难在于我们需要支持固定模式前缀的许多范围添加，这建议将问题转化为管理“有多少个活动查询覆盖具有给定偏移量的每个位置”形式的贡献。 

重新解释该过程的一个有用方法是考虑每个位置$i$，涵盖它的所有查询。 对于固定查询$[l, r]$, 对职位的贡献$i$取决于$i - l + 1$。 因此，我们希望通过偏移量来聚合贡献，而不是迭代每个位置的查询或每个查询的位置。 

这里的标准技巧是通过破坏函数来处理贡献$f(x)$转换为可以通过多个对齐序列上的差异数组进行处理的组件。 关键结构是最低有效集位将整数划分为大小为 2 的幂的块。 在每个块内，LSB 是恒定的，这使得$f(x)$转换为区间上的分段线性函数$[2^k, 2^{k+1})$。 

这使我们能够将每个查询贡献分解为$O(\log n)$每个块结构的算术段，并使用差异数组应用范围加法。 而不是触摸每一个$x$，我们更新整个二次幂对齐区间。 

这将每个查询从线性时间减少到对数时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(\sum (r-l+1))$|$O(n)$| 太慢了 |
 | 最佳 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们利用的结构$f(x)$在最低有效设置位恒定的范围上。 

1. 不预先计算超过 n 的全局数组，因为所有值仅取决于 x 直至 n。 对于每个$x$，我们没有显式存储$f(x)$，但我们依赖它的块结构。 
2. 对于每个查询$[l, r]$，我们将贡献解释为添加$f(1)$到$l$,$f(2)$到$l+1$，依此类推，直到$f(r-l+1)$。 这是一个前缀对齐的模式。 
3.分解偏移范围$x \in [1, r-l+1]$分成段，其中$\text{lowbit}(x)$是恒定的。 这些段正是范围$[2^k, 2^{k+1}-1]$。 
4. 对于每个这样的细分，计算贡献公式。 在一个段上，其中$\text{lowbit}(x) = 2^k$，我们有$$f(x) = x \cdot 2^k$$这是线性的$x$。 
5. 对于固定段$[L, R]$，我们需要添加$x \cdot 2^k$到职位$i = l + x - 1$。 扩展此给出：$$x \cdot 2^k = (i - l + 1) \cdot 2^k = i \cdot 2^k - (l - 1)\cdot 2^k$$因此，每个段都成为线性函数的范围更新$i$。 
6. 维护两个差异数组：一个用于系数$i$，还有一个用于常数。 每个部分贡献：

 系数数组的线性范围更新，

 以及对常量数组的相应范围更新。 
7. 处理完所有查询后，计算两个数组的前缀和以恢复每个位置的最终值。 

### 为什么它有效

 每个查询都被分解为不相交的二次幂段，其中最低有效设置位是固定的。 在每个段内，函数在目标索引中变为线性。 由于线性函数在范围加法下是封闭的，因此我们可以使用差异数组聚合所有贡献而不会丢失信息。 最终的重建只是将每个位置的所有主动线性贡献相加。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, q = map(int, input().split())
        
        A = [0] * (n + 2)
        B = [0] * (n + 2)
        
        for _ in range(q):
            l, r = map(int, input().split())
            length = r - l + 1
            x = 1
            
            while x <= length:
                k = (x & -x)
                start = x
                end = min(length, (x | (k - 1)))
                
                L = l + start - 1
                R = l + end - 1
                
                # f(x) = x * k = i*k - (l-1)*k
                A[L] += k
                A[R + 1] -= k
                
                B[L] += (-(l - 1) * k)
                B[R + 1] -= (-(l - 1) * k)
                
                x = end + 1
        
        curA = curB = 0
        res = []
        for i in range(1, n + 1):
            curA += A[i]
            curB += B[i]
            res.append(str(curA * i + curB))
        
        out.append(" ".join(res))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现维护两个差异数组。 将线性项的系数存储在$i$，另一个存储常量。 每个块更新对应一个范围，其中$f(x)$行为呈线性，因此我们将其转换为原始索引范围上的仿射更新。 

最后一遍通过累加两个分量并评估来重建值$a_i \cdot i + b_i$在每个位置。 

主要的微妙之处在于偏移量之间的仔细映射$x$和实际索引$i$，尤其是转变$i = l + x - 1$。 这里任何相差一的错误都会破坏线性分解。

 ## 边缘情况

 一个关键的边缘情况是当查询在同一前缀上严重重叠时。 在这种情况下，如果忘记了移位，幼稚的实现可能会错误地重复计算偏移量$i - l + 1$。 在此解决方案中，移位被吸收到仿射变换的常数项中，因此重叠查询只需添加它们的系数。 

另一个边缘情况是当$r = l$。 那么只有$x = 1$贡献，并且自从$lowbit(1) = 1$，更新减少为单点加法 1。分解仍然恰好产生一个段，因此不需要特殊处理。 

第三种边缘情况发生在块边界处，例如$x = 8, 16, 32$。 这些正是最低有效设置位发生变化的地方，并且不正确的分组会混合不同的线性函数。 二进制块分解确保这些边界是隔离的，从而保持正确性。
