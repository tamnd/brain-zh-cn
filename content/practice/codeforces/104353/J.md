 ## 解决方案
 ## 问题理解

 该网络是一棵以节点 1 为根的树。每条边代表一条具有延迟值的双向物理链路。 对于任何节点 x，通信成本 f(x) 是从根到 x 的唯一路径上的边权重之和。 目标是最小化所有节点上这些根距离的总和。 

您最多可以执行 k 次操作。 每个操作选取一条边，并将其权重 t 替换为通过向上舍入 t/2 获得的值。 可以多次选择相同的边，并且每次其当前权重在这种舍入意义上减半。 

更改边的影响对于单个节点来说不是局部的。 如果一条边位于大小为 s 的子树上方，则该子树中的每个节点的根距离都会发生完全相同的变化量。 这意味着一条边对总答案的贡献是它的权重乘以其后代子树的大小。 

这些约束将解决方案推向接近线性或 n log n 行为。 节点数量可以达到200万，而操作数k可以高达10亿。 这种组合排除了任何一一模拟操作的策略。 它还清楚地表明我们无法显式存储或处理 k 个步骤； 相反，我们必须将每次操作视为选择当前最佳的可用改进。 

将减半操作视为一次性收益会带来一个微妙的陷阱。 例如，权重为3的边经过一次操作后变为2，然后2变为1，然后1再次变为1。 边际收益迅速缩小并最终消失。 任何假设每条边最多贡献一次改进的解决方案都会低估大权重的长链减少。 

另一个常见的失败来自于忽略子树的多重性。 考虑一个以 1 为根、边权重为 10 的星形。就路径结构而言，减少一条边仅影响一个叶子，但如果该叶子是更深树中的大子树的根，则相同的减少将因子树大小而放大。 缺少这个乘数会导致完全不同的贪婪排序。 

## 方法

 如果我们忽略操作限制并尝试直接模拟，自然的想法是重复选择一条边，应用减半，重新计算所有根距离，并重复 k 次。 每次重新计算所有距离的成本为 O(n)，执行 k 次就会得到 O(nk)，当 k 达到 10^9 时，这是完全不可行的。 

即使通过维护子树大小和更新受影响的路径来稍微改进这一点，仍然给我们带来相同的核心问题：我们需要全局决定每一步操作哪个边，并且每个操作的好处随着时间的推移而变化。 

关键的观察结果是每条边都是独立演化的。 树结构永远不会改变，只有边权重会改变。 此外，边缘上的每个操作都会产生明确定义的总和减少，并且同一边缘上的未来操作会产生可预测的增益递减序列。 

如果一条边的权重为 t 并且其子树大小为 s，则该边对总答案的贡献为 t 乘以 s。 经过一次操作后，权重变为 ceil(t/2)，因此增益为 t - ceil(t/2)，按 s 缩放。 之后，相同的模式会在新的重量上重复。 这会产生每个边缘增益递减的序列。 

整个问题变成从潜在增益的多重集中选择最多 k 个元素，其中每条边生成一串递减的值。 最佳策略始终是接下来获取最大的可用增益，因为除了每次消耗一个单位的 k 之外，操作是独立的。

为了有效地支持这种选择，我们使用最大堆。 最初，我们计算每条边的第一个增益。 每次我们弹出最佳增益时，我们都会应用它，然后推动同一边缘的下一个增益（如果它仍然为正）。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(nk) | O(nk) | O(1) | O(1) | 太慢了 |
 | 贪婪的收获 | O((n + k) log n) | O((n + k) log n) | O(n) | 已接受 |

 ## 算法演练

 我们以节点 1 为树根并使用单个 DFS 计算子树大小。 这是必要的，因为每条边的贡献随着其下方的节点数量而变化。 

然后，我们通过将每条边的权重乘以其子树大小求和来计算总初始成本。 

对于每条边，我们还计算其第一个可能的改进，即如果我们对该边应用一次减半操作，则总成本会降低。 

我们维护这些改进的最大堆，每个条目都与特定的边缘及其当前的权重状态相关联。 

k 个操作中的每一个操作如下进行。 我们提取当前总距离减少最多的边缘。 我们从答案中减去这个值，因为我们正在应用它。 然后，我们将该边的权重更新为减半值，并计算该边的下一个可能的改进。 如果该改进不为零，我们会将其插回到堆中。 

这个过程一直持续到我们使用完所有 k 个操作或者堆变空，这意味着在任何边上都不可能进一步减少。 

这种方法起作用的关键原因是，每个操作都会产生一个确定性增益，该增益仅取决于一个边缘的当前状态，并且应用它不会干扰其他边缘的增益值。 全局目标纯粹是边缘的累加，因此在每一步中选择最佳的边缘改进可以保持最优性。

import sys
input = sys.stdin.readline

import heapq

def solve():
    n, k = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    edges = []
    
    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        g[u].append((v, w, len(edges)))
        g[v].append((u, w, len(edges)))
        edges.append((u, v, w))
    
    parent = [0] * (n + 1)
    parent_edge = [-1] * (n + 1)
    stack = [1]
    order = []
    
    parent[1] = -1
    
    while stack:
        u = stack.pop()
        order.append(u)
        for v, w, idx in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            parent_edge[v] = idx
            stack.append(v)
    
    sz = [1] * (n - 1)
    
    for u in reversed(order):
        for v, w, idx in g[u]:
            if parent[v] == u:
                sz[idx] += sz[v]
    
    cur = []
    total = 0
    
    weights = [0] * (n - 1)

        if parent[u] == v:
            child = u
        else:
            child = v
        weights[_] = w  # placeholder (we fix below)

    weights = [0] * (n - 1)
    for i, (u, v, w) in enumerate(edges):
        weights[i] = w

        return (w // 2) * s
    
    h = []

        total += w * sub[i]
        g0 = gain(w, sub[i])
        if g0 > 0:
            heapq.heappush(h, (-g0, i, w))
    
    k = int(k)
    
    while h and k > 0:
        gval, i, w = heapq.heappop(h)
        gval = -gval
        if gval == 0:

        total -= gval

```实现的核心是将树转换为有根形式，以便每条边都知道其子树的大小。 DFS 顺序用于反向计算子树大小。 

堆存储每个边的下一个可用改进。 每个条目包含当前增益、边缘索引及其当前权重。 应用增益后，边缘将被更新并重新插入（如果它仍然可以发挥作用）。 

一个常见的微妙问题是在迭代遍历中错误地重新计算子树大小。 正确的解释是子树大小在任何操作之前都是固定的，因为改变边权重不会改变树结构。 

## 工作示例

 考虑一棵小树，其中节点 1 连接到节点 2 和 3，边权重分别为 5 和 7，k 等于 2。 

最初，两条边的子树大小均为 1。初始增益分别为 2 和 3。 堆从 (3 从边 1-3 开始) 和 (2 从边 1-2 开始)。

 该轨迹显示了同一条边如何在多个操作中保持最佳状态，因为它最初的权重较大，会产生更长的效益序列。 

现在考虑权重为 8 和 6 的线性链 1-2-3，k 等于 3。 

| 步骤| 边缘 | 增益| 之后的重量 | 总减少量|

 ## 边缘情况

 单边树显示了最简单的行为，其中所有操作都应用于一个增益递减序列。 该算法重复从同一边缘提取收益，直到其收益消失，与预期的几何衰减相匹配。 

深链强调子树大小计算的正确性。 每条边都有不同的乘数，具体取决于其下方有多少个节点，并且算法会正确地优先考虑影响力较高的边，即使它们的原始权重较小。 

均匀的星形结构测试堆是否正确打破平局。 由于所有子树大小相同，因此决策仅取决于权重减少链，并且算法自然地根据剩余增益大小在边缘之间交替。
