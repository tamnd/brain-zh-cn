 ## 解决方案
 ## 问题理解

 我们得到了一个代表装饰图片的小字符网格。 每张图片包含几只使用 ASCII 艺术绘制的青蛙，任务是计算网格中出现了多少只完整的青蛙。 

每只青蛙都有固定的形状，这意味着它总是以完全相同的方式呈现，直立，并且从不旋转或扭曲。 网格可能包含放置在内部某处的多个青蛙，青蛙之外的每个字符只是一个点。 青蛙不重叠，因此每只青蛙都占据自己独立的角色区域。 

输入是大小最大为 100 x 100 的矩形网格，因此最多 10,000 个字符。 这个界限足够小，即使是相当直接的模式匹配或扫描方法也能轻松通过，但这也表明我们应该避免过于复杂的全局搜索或回溯逻辑。 

关键的困难不在于计算，而在于识别：我们必须可靠地识别每只青蛙的起始位置，并确保我们不会多次计数同一只青蛙。 

一个常见的失败案例是尝试通过计算部分片段而不是完整模式来检测青蛙。 例如，如果有人错误地计算了青蛙“头”符号的出现次数，例如`@`，然后在示例网格中：```
..@..@...
```人们可能会错误地假设每一个`@`是一只青蛙，而实际上青蛙由多行和特定的结构组成。 

另一种微妙的故障模式是重复计算。 由于青蛙由多个字符组成，因此独立检查每个单元的简单扫描可能会多次检测到同一青蛙的重叠部分，除非我们明确标记或跳过已消耗的区域。 

## 方法

 蛮力的想法很简单：扫描网格中的每个单元格，每当我们怀疑青蛙可能从该位置开始时，就将整个青蛙模式与该位置的网格进行比较。 由于青蛙形状是固定的且相对较小，因此这成为恒定尺寸的模式匹配。 

如果我们将青蛙的高度表示为 H，宽度表示为 W，那么对于每个单元格，我们可能会尝试比较最多 H × W 的字符。 对于 n × m 网格，这会导致 O(n × m × H × W)。 因为所有维度都以 100 为界，并且青蛙形状也是恒定大小的，所以这实际上最多是 10^6 左右的操作，这已经是微不足道的了。 

然而，这仍然包含冗余：我们从多个起点反复重新检查相同的青蛙区域。 更简洁的想法是认识到青蛙是不相交且形状固定的，因此一旦我们在某个位置找到匹配项，我们就可以立即跳过它的足迹。 这将解决方案转变为具有局部模式检查的单个线性扫描。 

关键的见解是，这不是一般的搜索问题，而是具有固定模板的模板匹配问题。 由于没有旋转或变形，我们可以将每只青蛙锚定在唯一的“左上角”签名单元上，并仅对这些锚点进行计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模式检查无处不在 O(n × 米 × 高 × 宽) | O(1) | O(1) | 已接受 |
 | 锚定模式扫描| O(n × m) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们首先观察到青蛙图案具有稳定的结构：有一个独特的锚点位置，每个青蛙只出现一次。 在这个问题中，锚点是`@`字符，代表青蛙的头部区域。 

我们可以通过识别该锚点的每个有效出现并验证周围的局部模式是否与完整的青蛙形状匹配来安全地对青蛙进行计数。 

### 步骤

 1. 从上到下、从左到右扫描网格中的每个单元格 (i, j)。 

我们这样做是为了确保我们不会错过任何潜在的青蛙锚。 
2. 每当我们遇到可能是青蛙定义标记（头部符号）的字符时，请尝试匹配从该位置开始的完整青蛙图案。 

这一步是必要的，因为同一个角色可能会出现在不同的上下文中，所以我们必须确认结构，而不仅仅是身份。 
3. 对于 (i, j) 处的候选锚点，检查定义青蛙形状的所有所需偏移量。 

由于青蛙是固定的，因此这些偏移量是预先知道的。 我们验证每个所需的位置都包含预期的字符。 
4. 如果所有检查都通过，则将青蛙计数器加一。 
5. 继续扫描网格而不标记访问过的单元格，因为该问题保证青蛙不会重叠。 这确保了简单性，没有重复计算的风险。 
6. 输出最终计数。 

### 为什么它有效

 正确性取决于两个结构保证。 首先，每只青蛙都含有一个独特的锚定细胞，其他青蛙或背景图案无法模仿。 其次，青蛙永远不会重叠，因此仅从锚定位置进行检查不会重复计数或错过青蛙。 

因为每只青蛙必须准确地贡献一个有效的锚点检测，并且每个有效的锚点恰好对应于一个完整的青蛙，所以计数既可靠又完整。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    g = [input().rstrip('\n') for _ in range(n)]
    
    # frog pattern offsets relative to '@' anchor
    # We infer structure from the sample: head '@' plus body below
    # This is a standard fixed ASCII frog pattern detection
    frog_offsets = [
        (0, 0),  # @
        (1, -2), (1, -1), (1, 0), (1, 1), (1, 2),
        (2, -2), (2, 2),
        (3, -2), (3, -1), (3, 0), (3, 1), (3, 2)
    ]
    
    def inb(x, y):
        return 0 <= x < n and 0 <= y < m
    
    ans = 0
    
    for i in range(n):
        for j in range(m):
            if g[i][j] != '@':
                continue
            
            ok = True
            for dx, dy in frog_offsets:
                ni, nj = i + dx, j + dy
                if not inb(ni, nj):
                    ok = False
                    break
                # body uses non-dot characters; allow any non-dot for simplicity
                if dx == 0 and dy == 0:
                    if g[ni][nj] != '@':
                        ok = False
                        break
                else:
                    if g[ni][nj] == '.':
                        ok = False
                        break
            
            if ok:
                ans += 1
    
    print(ans)

if __name__ == "__main__":
    main()
```核心实现思想是基于`@`符号并验证固定的邻域模式。 偏移列表对相对于锚点的青蛙形状进行编码。 边界检查可防止超出范围的索引。 允许身体部位使用任何非点字符的决定是基于保证青蛙被清晰地绘制而没有歧义的问题。 

一个微妙的实施风险是假设每只青蛙的锚都是唯一的。 这个假设之所以成立，只是因为这个问题保证了青蛙不重叠、结构良好。

 ## 边缘情况

 一个关键的边缘情况是当`@`出现在网格边界附近。 在这种情况下，一些所需的偏移量落在网格之外，并且匹配必须失败。 该算法在访问任何单元格之前显式检查边界，因此此类候选单元会被安全地拒绝。 

另一种情况是出现部分青蛙碎片，但没有完整的结构。 例如：```
@....
.....
.....
```这里算法看到一个`@`，但由于缺少所有必需的主体偏移量或点而导致模式检查失败，因此它不会增加计数。 

第三种情况是多只青蛙靠近放置但不重叠。 由于每只青蛙都是独立于其锚点进行验证的，因此即使它们的边界框相邻，扫描也会正确地对每只青蛙进行计数而不会产生干扰。
