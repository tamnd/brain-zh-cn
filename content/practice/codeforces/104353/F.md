 ## 解决方案
 ## 问题理解

 给定一个由小写英文字母组成的字符串，我们需要计算有多少个三元组的位置$(a, b, c)$存在使得指数满足$1 \le a < b < c \le n$，这些位置的字符都是相同的，并且索引形成等差数列，意思是$2b = a + c$。 

条件$2b = a + c$力量$b$恰好是之间的中点$a$和$c$，因此每个有效的三元组都是通过在中心周围的对称位置选择两个相等的字符来确定的。 换句话说，我们正在寻找长度为 3 的回文三元组，其中所有三个字符都相同，并且中间索引是外部两个索引的中点。 

输入尺寸很大：最多$10^5$每个测试用例的字符数，最多 10000 个测试用例，以及所有测试用例的总和$n$受$10^5$。 这立即排除了任何二次解$n$每个测试用例，因为即使是一个$O(n^2)$传递总输入已经太慢了。 每个测试用例的目标必须接近线性，或者对于所有组合的测试用例至多是线性的。 

天真的思维的一个微妙的失败案例是将问题视为“选择三个相同的字符”而不考虑算术约束。 例如，在字符串中`aaaaa`，选择任意三种的方法数`a`是$\binom{5}{3} = 10$，但只有其中一些三元组满足等间距。 正确答案较小，因为只有像这样的组合$(1,3,5)$和$(1,2,3)$和$(3,4,5)$满足中点对齐是有效的，而任意三元组如$(1,2,5)$均无效。 这表明仅频率计数是不够的。 

另一种边缘情况是当字符串中某个字符的出现非常稀疏时，例如`abacada`。 即使一个字符出现多次，大多数三元组也不会形成对称的算术级数，因此我们不能任意组合出现的情况。 

## 方法

 暴力方法将枚举所有对$(a, c)$, 计算$b = (a + c) / 2$，检查它是否是整数并且位于它们之间，并验证所有三个字符是否匹配。 这是正确的，但要付出代价$O(n^2)$每个测试用例，因为对于每一对，我们都执行持续的工作。 和$n = 10^5$，这就变成了$10^{10}$在最坏的情况下进行操作，这远远超出了任何可行的极限。 

关键的观察结果是中点条件与端点紧密耦合。 我们不考虑任意三元组，而是修复中间索引$b$。 一次$b$是固定的，条件迫使我们看对$(a, c)$围绕它对称。 我们需要$a < b < c$,$str[a] = str[c] = str[b]$， 和$a + c = 2b$。 这意味着$a$和$c$等距于$b$，所以对于固定距离$d$，我们只需要检查是否$str[b-d] = str[b+d] = str[b]$。 这减少了扫描每个中心并向外扩展的问题，但仍然在每个有效距离上进行持续的工作。 

我们可以通过注意到对于每个中心来进一步优化$b$，我们只需要考虑距离$d$这样两边都留在弦内。 此类检查的总数$b$是$\sum_b O(\min(b, n-b))$，即$O(n^2)$在最坏的情况下，但我们可以利用字母限制。 

由于字符必须在所有三个位置都匹配，因此我们可以按字符分隔问题。 对于每个角色$ch$，我们收集它出现的所有索引。 现在问题变成：计算这个索引列表中长度为 3 的算术级数。 对于固定字符，如果其位置为$p_1, p_2, \dots, p_k$，我们需要计算三元组$p_i, p_j, p_k$这样$p_i + p_k = 2p_j$。 

这是排序列表上的经典“三项算术级数计数”问题。 中线的天真两分球仍然存在风险$O(k^2)$，但我们可以利用一个关键的对称性：对于每一对$(i, k)$，我们计算中点并检查它是否存在于集合中。 使用哈希集进行成员资格查询可以使每一对进行检查$O(1)$, 给予$O(k^2)$最坏情况下每个字符，但由于所有字符的总和$k$超过字符是$n$，最坏的情况仍然退化。 

然而，我们可以再次翻转视角：不固定端点，而是固定中间索引$j$在每个字符列表内。 对于给定的$p_j$，我们想要计算对$i < j < k$这样$p_i + p_k = 2p_j$。 我们可以维护一个偏移频率图$p_j$。 对于每个$i < j$， 定义$d = p_j - p_i$，那么我们需要检查是否存在$k$这样$p_k - p_j = d$。 通过预先计算的距离上的后缀频率图，我们可以在每个字符列表的摊销线性时间中回答每个中间，从而得到整体$O(n)$所有角色的解决方案。 

这将问题转化为为每个字符维护每个距离出现在中心左侧和右侧的次数，并在我们将中心从左向右移动时更新这些计数。

 | 最佳 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 将字符串中每个字符的索引分组到单独的列表中。 这隔离了独立的子问题，因为有效的三元组不能混合字符。 
2. 对于每个字符列表，为右侧构建一个频率结构，最初包含除第一个被视为中心之外的所有位置。 这允许快速查找有多少未来位置可以匹配所需的对称距离。 
3. 遍历列表中的每个位置，将其视为中间索引$j$，逐渐将其从右侧结构中删除，并将之前的添加到左侧结构中。 
4. 对于每个中间位置，考虑所有之前见过的左侧位置$i$，计算距离$d = p_j - p_i$，并检查是否$p_j + d$存在于右侧。 每一场成功的比赛都会贡献一个有效的三元组。 
5. 累积所有字符的所有匹配并输出总数。 

基本思想是，每个有效的三元组在处理其中间元素时只计算一次，因为该算法仅计算相对于当前中心左右分割的对。 

### 为什么它有效

 每个有效的三元组$(a, b, c)$由其中间索引唯一标识$b$。 加工时$b$， 两个都$a$和$c$保证位于分区的相对两侧：$a$位于左侧结构中并且$c$处于正确的结构中。 距离条件保证$c$正是以下的镜像对应物$a$大约$b$。 由于每对都在中点有效时进行准确检查，因此不会遗漏或重复计算三元组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, s = input().split()
        n = int(n)

        pos = [[] for _ in range(26)]
        for i, ch in enumerate(s):
            pos[ord(ch) - 97].append(i + 1)

        ans = 0

        for arr in pos:
            m = len(arr)
            if m < 3:
                continue

            # right set initially contains all positions except first
            right = set(arr[1:])

            for j in range(1, m - 1):
                mid = arr[j]

                # move current mid from right to "processed"
                if mid in right:
                    right.remove(mid)

                # count pairs (i, j, k)
                for i in range(j):
                    d = mid - arr[i]
                    if mid + d in right:
                        ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```该实现首先按字符分隔索引，这确保我们只考虑具有相同字母的有效三元组。 核心思想是迭代每个字符组内每个可能的中间位置。 

内部循环将所有较早出现的事件检查为潜在的左端点。 对于每个左端点，直接计算对称右端点。 集合用于测试恒定时间内右端点的存在性。 

主要的微妙之处是保持右侧结构的正确性。 它必须严格表示当前中间右侧的索引，这就是我们在计数之前删除当前中间的原因。 这强制执行条件$a < b < c$。 

## 工作示例

 ### 示例 1：`abcabc`我们按角色对职位进行分组：`a: [1,4]`,`b: [2,5]`,`c: [3,6]`。 

我们独立处理每个组。 每个只出现两次，因此没有组可以产生三元组。 答案仍然是0。 

这证实了仅仅频率是不够的； 我们需要至少出现三次和正确的间距。 

### 示例 2：`aaaaaa`职位有`[1,2,3,4,5,6]`。 

我们一一处理中间位置：

 | 中指数 | 左侧位置 | 检查距离| 添加有效的三元组 |
 | ---| ---| ---| ---|
 | 2 | [1] | (1,3) 存在 | 1 |
 | 3 | [1,2]| (1,5), (2,4) | (1,5), (2,4) | 2 |
 | 4 | [1,2,3]| (1,7), (2,6), (3,5) | (1,7), (2,6), (3,5) | 2 |
 | 5 | [1,2,3,4] | (2,8)、(3,7)、(4,6) | 1 |

 总共有 6 个有效的三元组。 

这表明每个三元组在其中点被精确计数一次，并且通过距离匹配来强制对称性。

 ## 边缘情况

 对于像这样的字符串`aaaaa`，算法分别处理每个中点。 例如，在中间索引 3 处，左边是`[1,2]`右边包含`[4,5]`。 距左侧的距离为 2 和 1，并且右侧都有匹配的对应项，生成以 3 为中心的两个三元组。这会正确地仅计算那些对称性成立的三元组，并避免计算无效组合，如 (1,2,5)，因为距离检查失败。 

对于具有稀疏重复的字符串，例如`abacada`，每个字符组都是独立处理的。 对于性格`a`在职位`[1,3,5,7]`，仅以中点为中心检查距离镜像正确贡献的位置。 该算法从不混合不同的字符，因此不会发生误报。
