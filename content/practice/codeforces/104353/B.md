 ## 解决方案
 ## 问题理解

 问题中的流程是由从第一天开始的漫长的时间线驱动的。每天，zy 都应该在早上向 Belmaxi 发送固定金额（5 个单位）。 唯一与此例程不同的是，在某些特定的日子里，zy 忘记汇款。 

还有每 7 天进行一次的每周检查，始终保持一致，以便第 1 天是星期四，每天 7k+1 也是星期四。 在每个星期四结束时（特别是在第 7k+1 天 23:59），Belmaxi 会回顾截至该星期四的最后连续 7 天，并检查 zy 是否在所有这些天都成功汇款。 如果所有 7 天都“付费”，Belmaxi 会给 zy 50 个单位的奖励。 否则，那个星期四什么也不会发生。 

输入给出了总天数 n 以及 zy 忘记付款的天数的排序列表。 任务是计算 Belmaxi 的净利润：从 Belmaxi 的角度来看，每次成功付款都会贡献 +5，每周完美的 7 天连续贡献 -50，因为他支付了奖励。 

关键的挑战是 n 可以大到 10^16，因此每天迭代是不可能的。 相反，只有稀疏的故障天数才重要。 

7 天窗口重叠的方式会产生一个微妙的边缘情况。 错过一天可能会同时破坏多个每周奖励，相反，长期的成功可能会创建多个重叠的 7 天窗口，这些窗口都符合条件。 

例如，如果 n = 14 并且没有失误，则两周都会产生奖励。 净值为 14 * 5 − 2 * 50 = 70 − 100 = −30。 仅检查非重叠周的幼稚方法会错过第二个奖励。 

另一个边缘情况是当错过聚集在每周窗口边界周围时。 第 7 天的错过仅影响第一个窗口，但第 8 天的错过会影响第 7 天结束的窗口和第 14 天结束的窗口，具体取决于对齐情况。 

由于这些重叠和巨大的 n，问题简化为推理固定长度 7 的滑动窗口内错过了多少天，而无需逐日迭代。 

## 方法

 暴力视图会模拟从 1 到 n 的每一天，标记 zy 是否已付费，然后每天计算最后 7 天的窗口是否完整以及这一天是否是周四检查点。 从概念上讲，这是可行的：我们维护一个大小为 n 的数组，填充缺失的日期，并为每一天计算一个滑动窗口总和。 

然而，这是不可能的，因为 n 可以是 10^16，所以即使存储数组也是不可行的，更不用说迭代它了。 即使 n 只有 10^6，天真地重新计算 7 天窗口总和也会是 O(n) 或更糟，但仍然可以接受。 在这里，n 销毁任何每日方法。 

关键的观察结果是，奖励结构仅取决于以周四结束的每个 7 天片段是否完全“干净”。 由于星期四每 7 天出现一次，因此这些片段在端点上是不相交的，但在内容上是重叠的。 我们不是模拟日子，而是改变视角：每错过一天都会确定性地影响它影响的每周窗口数量。 

每个错过的日期 ai 最多影响 7 个连续的周四结束窗口，因为一天正好位于那些端点在其之后 6 天内的 7 天窗口中。 这使我们能够使用周而不是天的压缩索引上的范围计数来处理缺失天数对受影响周的贡献。 

我们可以将每周视为对应于天 [7k-6, 7k] 的索引 k。 ai 天的失误会影响所有 k，使得 7k-6 ≤ ai ≤ 7k，这会转化为 k 值的小整数范围。 我们不是迭代所有天，而是使用周索引的差异数组来累积每周的未命中次数。 处理完所有未命中后，仅当未命中计数为零时，一周才贡献 50。

这将问题简化为计算干净周数，加上收入总天数，两者都可以在 O(x) 中计算。

 | 暴力模拟| O(n) | O(n) | 太慢了 |
 | 几周的间隔压缩 | O(x) | O(x) | 已接受 |

 ## 算法演练

 我们首先以整周的形式重新解释时间表。 每个周 k 对应于从 7k−6 到 7k 的天段，并且只有终点日 7k 对奖励评估很重要。 当该段的所有 7 天都已支付时，奖励就会发生。 

接下来，我们计算完整周数 W = n // 7。任何超出 W * 7 的剩余天数都不会形成完整的检查窗口，并且与奖励无关。 

我们维护一个结构来跟踪每周间隔内有多少天缺失。 我们不是为每个缺失的日子单独标记每周，而是将每个缺失的日子 ai 转换为一系列受影响的周指数。 如果 7k−6 ≤ ai ≤ 7k，则 ai 日位于 k 周内，这相当于 k ∈ [(ai + 6) // 7, (ai // 7)]。 我们使用整数周范围内的差异数组来增加所有此类周的未命中计数。 

处理完所有缺失的日期后，我们扫描第 1 周到 W 周，累积缺失的前缀和。 每周零失误贡献 50 的奖励，除了错过的之外，每天始终贡献 5 的基本收入。 

最后，我们将贡献合并起来：总收入为 5 * (n − x)，总支出为干净周数的 50 倍。 

### 为什么它有效

 每周的奖励仅取决于 7 天间隔内是否有缺失的一天。 从天指数到周指数的转换准确地保留了这种条件，因为每个错过的日子都精确地映射到其间隔包含它的周集。 差异数组确保每周正确聚合所有贡献，并且除此计数之外，不相交的周间隔之间不存在交互。 这保证了前缀积累后，每周都被正确分类为干净或不干净。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split())) if x else []

        # total base income from successful payments
        total_income = 5 * (n - x)

        W = n // 7  # number of full weeks that can produce rewards

        diff = [0] * (W + 3)

        for day in a:
            # compute affected week range [L, R]
            L = (day + 6) // 7
            R = day // 7

            if L <= R:
                if L <= W:
                    diff[L] += 1
                    if R + 1 <= W:
                        diff[R + 1] -= 1

        clean_weeks = 0
        cur = 0
        for i in range(1, W + 1):
            cur += diff[i]
            if cur == 0:
                clean_weeks += 1

        total_reward = 50 * clean_weeks
        out.append(str(total_income - total_reward))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```核心转变是日指数向周指数的转换。 公式`(day + 6) // 7`和`day // 7`定义受影响周数的范围。 +6 偏移可确保任何一天正确地溢出到其包含的 7 天窗口中，即使它接近边界也是如此。 

差异数组避免明确标记每个受影响的周的每个错过的日子。 每次未命中仅贡献 O(1) 更新，而不是更新潜在的 O(7x) 位置，并且最终扫描解决实际计数。 

基本收入计算`5 * (n - x)`是安全的，因为每个非缺失的日子总是贡献一笔 5 单位的付款，与奖励无关。

 ## 边缘情况

 一个关键的边缘情况是错过的一天恰好位于一周边界上，例如第 7 天或第 14 天。对于 n = 14 且在第 7 天错过的情况，W = 2。错过映射到 L = 1，R = 1，因此只有第 1 周受到影响。 第 2 周保持干净并且仍然产生奖励。 这证实了边界映射不会错误地溢出到相邻的周。 

另一个边缘情况是，在时间线末尾附近存在不完整的周时，错过会聚集在一起。 例如，如果 n = 15 并且未命中发生在第 15 天，则根据公式，该天位于第 3 周，但由于 W = 2，因此完全忽略它。 该算法会安全地丢弃它，因为只有整周才能贡献奖励。 

最后一个微妙的情况是同一周内多次失误。 对于 n = 7 以及第 2、3 和 5 天的未命中，它们全部映射到第 1 周，并且前缀总和确保无论发生多少次未命中，该周都会被计为非干净的一次。
