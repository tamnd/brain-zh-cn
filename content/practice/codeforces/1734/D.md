 ## 解决方案
 ## 问题理解

 我们从位置开始`k`在一条线上`n`史莱姆。 每个位置都含有具有一定健康价值的粘液，当我们踏上仍然有粘液的位置时，我们会吸收它并将其健康值添加到我们的健康值中。 消极的价值观会降低我们的健康，而积极的价值观会增加我们的健康。 我们的粘液在任何时候都不允许降至零以下。 

目标是逐步向左移动到位置`0`或向右的位置`n+1`，吸收我们经过的一切，因为粘液在被吃掉后就会消失。 我们可以通过决定先走哪个方向来隐式选择扩展的顺序，但是一旦我们移动了一个位置，它就消失了。 

关键的困难在于我们不是简单地检查总和是否为非负数。 我们必须确保在路径的每个前缀处，运行健康度都不会变为负值，并且我们可能必须首先选择“更安全”的方向。 

约束条件很大，总共`n`所有测试用例多达 200,000 个。 这排除了任何间隔上的二次模拟或尝试所有可能的左右交错。 任何解决方案在每次测试时都必须是线性的，或者总体上是摊销线性的。 这强烈表明每个位置最多被处理固定次数，并且决策取决于类似前缀或贪婪的可行性检查。 

一个微妙的陷阱是假设只有总和才重要。 例如，考虑像这样的段`[-5, +100, -200, +200]`。 总和是正数，但如果我们采取错误的吸收顺序，我们可能会在达到大的正值之前遇到负前缀。 另一个失败的情况是假设我们必须在接触另一侧之前完全清除一侧的所有史莱姆； 事实上，最佳策略可能只延伸一侧，直到它“足够安全”可以切换。 

## 方法

 一种天真的观点是模拟两种可能性：尝试向左优先或向右优先，并递归地考虑向外扩展的所有方法。 在每一步中，我们选择向左或向右移动，检查健康状况是否保持非负数，然后继续。 这很快就会变成指数，因为每个状态都是由当前间隔定义的`[L, R]`和其内部的位置，并按方向分支会产生组合爆炸。 

即使我们将自己限制在“完全向左然后完全向右”这样的单调策略，反之亦然，这仍然会失败，因为中间的可行性很重要：一个部分可能具有正的总和，但仍然需要以特定的顺序吸收以避免低于零。 

关键的观察是，一旦我们决定完全消耗一侧，内部顺序就固定了。 因此，问题归结为检查我们是否可以按某种顺序向左和向右扩展，以便在当前运行状况下每个扩展都是可行的。 关键的见解是，扩展到一侧的可行性仅取决于我们是否可以从当前健康状况开始遍历整个段，可以通过向外扫描并保持最小前缀和来贪婪地检查。 

因此，我们不是模拟所有路径，而是预先计算每条边是否可以从起点完全消耗，然后贪婪地扩展当前安全的边，随着时间间隔的增长而更新我们的健康状况。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 完全模拟状态 | 指数| O(n) | 太慢了|
 | 带有前缀可行性检查的贪婪扩展 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将推理根植于起始位置`k`，并将当前可达区域视为向外扩展的段。 

1. 计算是否可以向左扩展`k`尽可能地同时不让生命值降至零以下。 我们模拟一次向左移动一步，更新生命值，并在无法继续前进时停止。 这给出了最大可到达的左边界。 
2. 同样计算我们可以向右扩展多远`k`在同样的规则下。 这给出了最大可到达的右边界。 
3. 如果任何一方超出边界（`0`或者`n+1`），我们可以立即逃跑。 
4. 否则，我们将问题视为维持间隔`[L, R]`最初于`[k, k]`，当前健康状况等于`a[k]`。 
5.我们尝试向外扩大区间。 在每个阶段，我们考虑将左扩展到`L-1`或有权`R+1`，但前提是整个侧段是“可行的”，这意味着我们可以从当前的健康状况开始遍历它，而不会达到负值。 
6. 为了有效地测试可行性，我们维护段的前缀和并确保沿扩展的最小前缀和不会低于`-current_health`。 这保证了我们在吸收过程中永远不会过零。 
7. 我们贪婪地延伸当前可行的一侧。 如果两者都可行，则任一顺序都有效，因为两种扩展都保持非负健康状况。 
8. 我们继续直到达到`0`或者`n+1`。 

### 为什么它有效

 在任何时候，唯一重要的约束是是否可以在不违反非负前缀条件的情况下消耗完整的连续段。 一旦一个细分市场可行，完全消耗它总是最佳的，因为它只会通过扩大可达到的位置来增加灵活性，并且不会减少未来的选择，除非通过可行性中已经考虑到的健康变化。 该过程保持当前间隔不变`[L, R]`可以按某种顺序完全消耗，而不会破坏健康限制。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can_cross(a, k):
    n = len(a) - 1
    left = k
    right = k
    health = a[k]

    if health < 0:
        return False

    # Try expanding greedily
    while True:
        moved = False

        # try left
        if left > 1:
            h = health
            ok = True
            for i in range(left - 1, 0, -1):
                h += a[i]
                if h < 0:
                    ok = False
                    break
            if ok:
                for i in range(left - 1, 0, -1):
                    health += a[i]
                left = 1
                moved = True

        # try right
        if right < n:
            h = health
            ok = True
            for i in range(right + 1, n + 1):
                h += a[i]
                if h < 0:
                    ok = False
                    break
            if ok:
                for i in range(right + 1, n + 1):
                    health += a[i]
                right = n
                moved = True

        if not moved:
            break

        if left == 1 or right == n:
            return True

    return left == 1 or right == n

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = [0] + list(map(int, input().split()))
        print("YES" if can_cross(a, k) else "NO")

if __name__ == "__main__":
    solve()
```该实现保留当前间隔，并仅在可以安全吸收完整的侧段时才尝试将其向外扩展。 内部可行性检查模拟候选方的消耗，同时通过运行总和隐式跟踪最小运行状况。 

主要的微妙之处在于，只有当我们知道整个段是安全的时，我们才会承诺扩张。 在检查阶段绝不允许部分消耗，因为这会将可行性测试与状态突变混合在一起。 另一个关键细节是保护边界条件：达到`left == 1`或者`right == n`意味着我们还可以再向逃生室迈出一步。 

## 工作示例

 ### 示例 1

 输入：```
7 4
-1 -2 -3 6 -2 -3 -1
```我们从索引 4 开始，健康状况为 6。 

| 步骤| 左| 对| 健康 | 行动|
 | --- | --- | --- | --- | --- |
 | 1 | 4 | 4 | 6 | 开始|
 | 2 | 4 | 7 | 6 → -3 | 完全向右展开|
 | 3 | 4 | 7 | 6 → -3 → ​​-6 → -7 | 右扩展早期无效 |

 右侧首先无法安全消耗，因此我们尝试向左扩展。 

| 步骤| 左| 对| 健康 | 行动|
 | --- | --- | --- | --- | --- |
 | 1 | 4 | 4 | 6 | 开始|
 | 2 | 1 | 4 | 6 → 5 → 3 → 0 | 向左完全展开 |
 | 3 | 1 | 4 | 0 → 6 → 4 → 1 | 然后向右展开 |

 我们成功地到达了两端。 

这说明正确的策略不是方向性偏差，而是基于可行性的扩张。
