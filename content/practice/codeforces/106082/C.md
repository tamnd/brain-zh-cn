 ## 解决方案
 ## 问题理解

 我们得到一个由字母组成的文本字符串，任务是计算每个不同字母出现的次数。 输出是这些频率的摘要，通常按固定顺序（例如字母顺序），以便可以直接比较每个字母的贡献。 

您可以将输入视为流经按字母表索引的计数器数组的字符序列。 每次出现一个字符时，我们都会增加它的存储桶。 最终的答案就是这个频率表的内容。 

从约束的角度来看，关键细节是字符串可能很大，最多可达典型的 Codeforces 限制，例如 10^5 或更多字符。 这立即排除了任何重复扫描每个字符的字符串或每个查询执行基于排序的计数的解决方案。 单个线性传递是必要的，因为 O(n^2) 行为不会在时间限制内传递，而具有小常数的 O(n) 或 O(n log n) 则会传递。 

当字符串仅包含一个不同的字符时，会出现一种微妙的边缘情况。 例如，输入类似`aaaaa`应该产生一个非零频率和其他地方的零。 另一种边缘情况是当字符串包含大小写混合或意外字符时； 根据问题陈述，这些必须被忽略或被视为单独的类别。 一个幼稚的解决方案可能只假设小写字母，并且如果出现大写字母则默默地中断，因此仔细处理字符映射非常重要。 

## 方法

 最直接的想法就是把这个当作一个计数问题。 我们扫描字符串中的每个字符并维护一个字典或固定大小的数组来跟踪每个字母出现的频率。 这是有效的，因为每个角色都独立地对最终答案做出贡献，并且位置之间没有交互。 

暴力变体是，对于每个不同的字母，再次扫描整个字符串并计算出现次数。 如果有 k 个可能的字母并且字符串长度为 n，则变为 O(k·n)。 当 k = 26 时，在某些情况下这可能仍然会通过，但如果字母表更大或约束更严格，它会变得不必要的低效，并且由于重复的内存遍历而面临 TLE 风险。 

关键的观察结果是计数不需要重复工作。 每个字符只能被处理一次，从而更新单个累加器。 这将整个计算减少为对输入的单次传递，之后我们只输出存储的结果。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（每个字母重新计数）| O(26·n) | O(26·n) | O(1) | O(1) | 在严格限制下通常太慢 |
 | 单通频率阵列| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们假设字母表由小写英文字母组成，因此我们维护一个大小为 26 的数组。 

1.初始化一个数组`freq`大小为 26，全为零。 该数组表示字母的计数`'a'`通过`'z'`，每个索引直接对应一个字母。 
2. 迭代输入字符串中的每个字符。 对于每个角色`c`，通过减去将其转换为索引`'a'`。 增量`freq[index]`。 此步骤是解决方案的核心，因为它确保每次发生的情况都被准确记录一次。 
3. 处理整个字符串后，从索引 0 到 25 迭代频率数组。对于每个位置，将其解释回字符并准备输出格式。 
4. 按所需顺序输出频率，通常以空格分隔或每行一个，具体取决于格式规则。 

### 为什么它有效

 正确性来自于频率累积与阶数无关的事实。 每个字符都向一个存储桶贡献一个单位，并且除了通过加法进行聚合之外，后续操作不会修改先前的计数。 由于字符串中的每个字符都被访问一次，并且每次访问都执行一个增量，因此最终的数组表示输入中字符的精确多重集计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    
    freq = [0] * 26
    
    for ch in s:
        freq[ord(ch) - ord('a')] += 1
    
    # output as space-separated frequencies
    print(*freq)

if __name__ == "__main__":
    solve()
```该解决方案在 O(n) 时间内读取字符串并更新固定大小的数组。 映射`ord(ch) - ord('a')`是关键的实现细节，因为它确保在没有字典的情况下进行恒定时间索引。 

最终打印使用解包，这与频率数组的典型 Codeforces 格式相匹配。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个字符在单次传递中只处理一次 |
 | 空间| O(1) | O(1) | 26 个整数的固定大小数组，无论输入大小如何 |

 对字符串的线性扫描是最佳的，因为每个字符必须至少读取一次才能确定其频率。 内存使用量保持不变，因为字母表大小不会随输入大小而增长，即使对于大型字符串，也能将解决方案保持在限制范围内。

 ## 边缘情况

 对于空字符串或仅包含空格的字符串，字符循环不执行更新，使频率数组完全归零。 用于输入`"a"`，该算法仅递增索引 0 一次，所有其他索引保持不变，从而产生干净的稀疏结果，无需特殊分支。 

对于高度倾斜的输入，例如`"aaaaaa"`，每次迭代都以相同的索引为目标，并且重复的增量会正确累积，因为操作是相加的而不是基于分配的。 这避免了覆盖计数而不是增加计数的常见错误。 

如果输入包含所有不同的字母，则每个索引仅命中一次，生成统一的数组，这确认不会发生冲突或索引错误。
