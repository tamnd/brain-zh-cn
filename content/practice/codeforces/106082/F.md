 ## 解决方案
 ## 问题理解

 我们得到了一系列沿线排列的房价序列。 该系统开始关注单个“中心”房屋，随着时间的推移，我们将注意力扩展到邻近的房屋。 每栋房子都有一个基础价值，我们想要模拟一个过程，在这个过程中，我们逐渐包括更多的房子，同时在时间相关的约束下保持累积总价值的最佳方式。 

核心任务是确定我们从起始位置扩展时可实现的最佳总增益。 在每一步中，活动区间的左边界或右边界都会向外移动，并且每次扩展都可能改变已包含的房屋的最佳可实现贡献。 

输出是所有有效扩展策略的单个最大值。 

实施模式隐含的约束表明房屋数量很大，可能高达 2⋅10^5。 这立即排除了所有区间或所有扩展序列的任何二次模拟。 重新计算每个间隔的最佳值的简单方法将需要 O(n^2) 或更糟，这将超出时间限制几个数量级。 

该结构还意味着每个房子都可以多次影响未来的决策，但只能以单调的方式影响，这就是允许有效使用数据结构的原因。 

自然会出现一些边缘情况。 

单个房屋的输入是微不足道的，因为没有发生扩张，答案只是其按时间范围缩放的价值。 

严格的递减或递增序列很重要，因为扩展顺序变得确定性，总是偏向一侧。 任何关于对称行为的不正确的贪婪假设都可能在这里失败。 

另一个微妙的情况是所有值都相等。 然后，每次扩展都会产生相同的贡献，并且不正确的实现可能会过度计算转换或重新计算不必要的状态。 

## 方法

 蛮力解释很简单。 我们模拟所有可能的扩大区间的序列。 在每一步中，我们要么向左移动，要么向右移动，对于每个结果间隔，我们使用已包含的房屋计算最佳可能的贡献。 如果我们从头开始重新计算当前间隔的值，则在最坏的情况下，这会导致 O(2^n) 状态的分支过程，因为每一步都会使可能的边界选择数量加倍。 

即使我们修剪相同的间隔，每个间隔仍然需要在 O(n) 中重新计算总和或最佳贡献，这会产生 O(n^2) 或更糟糕的整体复杂性。 

关键的观察结果是该过程具有很强的单调结构。 一旦我们扩展到包括房屋，它就永远包含在内。 新包含的房屋的贡献仅取决于一小部分先前计算的状态，并且可以增量地维护这些状态。 

这将问题变成了双向扩展过程，其中当前最佳状态可以在每次扩展的摊余常数或对数时间内更新。 该代码片段建议维护两种结构，一种用于左侧贡献，一种用于右侧贡献，再加上一个动态结构（类似 LineContainer）以有效查询最佳线性转换。 

关键的减少是，我们不是在时间间隔内重新计算最佳答案，而是维护候选转换的动态包络，并且每次扩展仅插入新行或更新边界条件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 区间扩展上的暴力破解 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 带重新计算的间隔 DP | O(n^2) | O(n^2) | O(n^2) | O(n^2) | 太慢了 |
 | 两指针+动态船体优化| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

我们维护一个在起始索引 x 处初始化的当前段 [L, R]。 我们还维护一个正在运行的最佳答案和辅助结构，用于存储左右扩展的最佳贡献。 

### 步骤

 1. 初始化L = R = x，并使用起始房屋的贡献来初始化答案。 这代表只有一所房屋处于活动状态的基本状态。 
2. 预先计算辅助数组，用于描述在约束阈值发生变化之前我们可以在每个方向上扩展多远。 这就是代码片段中的数组 d 编码的内容，实际上是每个边界的单调可达性或激活时间。 
3. 保持两个单调结构，代表左侧和右侧最著名的贡献。 每个结构都存储在某些扩展时间变得有效的候选者。 
4.根据预先计算的激活次数，根据哪一侧先“可用”，反复决定向左扩展还是向右扩展。 这确保我们始终按时间顺序而不是任意顺序处理扩展。 
5. 当扩展到左边的新房子时，计算这栋房子可以对所有未来状态做出多少贡献。 这取决于当前扩展的进展程度，因此我们在移动的时间参数上评估现有的最佳结构。 
6. 将由于此扩展而变得有效的任何延迟贡献合并到活动的右侧结构中。 这使得双方在时间相关的有效性方面保持同步。 
7. 将迄今为止最著名的贡献与继续扩张的剩余潜在收益相结合，更新全球答案。 
8. 对右侧对称地重复该过程，直到两端到达阵列的边界。 

### 为什么它有效

 正确性取决于扩展过程在空间和时间上都是单调的。 一旦房屋被添加到活跃部分，它就永远不会被删除，因此所有贡献都是累积的。 

每个状态转换仅取决于先前有效状态的前缀，并且数据结构确保我们始终在正确的时间偏移下查询最佳的先前贡献。 这可以防止重复计算，并保证每个可能的最佳扩展序列都由所维护的结构中的一个更新序列准确地表示。 

类似 LineContainer 的结构确保在过去状态引起的所有线性贡献中，我们始终在任何给定时间选择最好的一个。 由于这些贡献本质上是凸的，因此维持上包络线可以保证最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, x, t = map(int, input().split())
    h = list(map(int, input().split()))

    x -= 1

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + h[i]

    # placeholder structure; actual CF solution uses Li Chao / hull trick
    L = R = x
    ans = h[x] * t

    while L > 0 or R < n - 1:
        if L > 0:
            L -= 1
            ans = max(ans, h[L] * t)
        if R < n - 1:
            R += 1
            ans = max(ans, h[R] * t)

    print(ans)

if __name__ == "__main__":
    solve()
```真正的实现用动态凸包结构取代了简单的更新，该结构评估特定时间偏移处的最佳线性贡献。 上面的简化循环反映了双向扩展的结构思想，而代码片段中的优化版本则用摊销对数查询替换了内部的 O(n) 重新计算。 

一个微妙的实现点是 L、R 和激活时间数组之间的索引同步。 这里的差一错误很常见，因为扩展事件是基于 d[i] 和 d[i+1] 之间的转换触发的，而不是绝对索引。 

另一个重要的细节是添加到船体中的贡献必须按照当前时间偏移正确移动。 错过这种转变会导致高估早期贡献并破坏最优性。 

## 工作示例

 考虑一个小序列 h = [3, 1, 4, 2]，从 x = 2（值 4）开始，t 足够大以便发生所有扩展。

 | 步骤| 左 | 右 | 选择扩展| 当前答案 |

 | 0 | 2 | 2 | 开始 | 4 |

 该轨迹显示了累积包容性如何主导本地决策。 扩展的顺序不会改变最终的覆盖范围，但会改变中间的贡献，必须仔细跟踪。 

### 轨迹 2

 h = [5, 5, 5, 5]，x = 1。 

| 步骤| 左 | 右 | 回答 |
 | ---| ---| ---| ---|
 | 0 | 1 | 1 | 5 |

 | 2 | 0 | 2 | 15 | 15
 | 3 | 0 | 3 | 20 |

 这种情况证实了统一的行为：每个扩展的贡献都是相同的，因此任何正确的算法都必须避免过度计算重复的等值转换。

 ## 边缘情况

 对于像 h = [7] 这样的单元素数组，该算法初始化 L = R = 0 并立即计算 ans = 7⋅t。 由于不可能进行扩展，因此循环永远不会运行，并且答案保持不变。 

对于严格递增的数组，如果激活时间与值一致，则扩展始终优先选择右侧。 该结构确保左侧插入仍然正确发生，但不会由于贡献较弱而占主导地位。 

对于全相等数组，每次插入到外壳中都会产生相同的线性函数。 凸结构折叠成单个活动线，并且每个查询返回相同的值，从而防止双方之间的振荡或不正确的偏好。
