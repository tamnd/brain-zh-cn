 ## 解决方案
 ## 问题理解

 我们在 2D 平面上得到一组不同的点。 任务是计算有多少个无序的点三元组形成一个配置，其中一个点正好位于由其他两个点形成的线段的中点。 

如果我们选三点$A$,$B$， 和$C$， 然后$B$是线段的中点$AC$什么时候：$B = \left(\frac{x_A + x_C}{2}, \frac{y_A + y_C}{2}\right)$由于三元组是无序的，因此该对$(A,B,C)$是一样的$(C,B,A)$。 我们只想对每个有效的几何配置计数一次。 

约束条件$n \le 3000$是问题的关键。 直接检查每个三元组的三次解需要大约$3000^3 = 27$十亿张支票，远远超出了 2 秒的时间限制。 二次解，大约 900 万次运算，在 Python 中是完全合理的。 

坐标很小，介于$-1000$和$1000$，但仅此还不足以构建一个基于网格的小型解决方案。 重要的观察是几何的：如果$B$是的中点$AC$，那么坐标$A$和$C$决定$B$独一无二。 

一些边缘情况可能会悄悄地破坏粗心的实现。 

考虑这个输入：```
3
0 0
1 1
2 2
```答案是：```
1
```观点$(1,1)$是的中点$(0,0)$和$(2,2)$。 

现在考虑：```
3
0 0
1 0
2 1
```答案是：```
0
```仅检查平均值是否为整数的简单实现可能会错误地计算此值。 的中点为$(0,0)$和$(2,1)$是$(1,0.5)$，点之间不存在。 

另一个微妙的问题是重复计算。 假设我们有：```
3
0 0
1 1
2 2
```如果我们迭代有序对$(A,C)$，那么两者$(0,0)\rightarrow(2,2)$和$(2,2)\rightarrow(0,0)$产生相同的中点。 粗心的解决方案会返回 2 而不是 1。 

一种更重要的情况是中点坐标为小数时：```
4
0 0
1 1
1 0
2 1
```的中点为$(0,0)$和$(1,1)$是$(0.5,0.5)$，这是无效的。 的中点为$(1,0)$和$(2,1)$是$(1.5,0.5)$，同样无效。 正确答案是 0。任何使用浮点运算的方法都会面临精度问题和不必要的复杂性的风险。 

## 方法

 最直接的解决办法就是暴力破解。 我们可以迭代每个不同点的三重点，并检查其中一个点是否是其他两个点的中点。 

对于每个三元组$(A,B,C)$，我们验证：$2x_B = x_A + x_C \quad \text{and} \quad 2y_B = y_A + y_C$这是可行的，因为中点坐标恰好是端点的平均值。 方法是正确的，但运行时间却是灾难性的。 有$\binom{3000}{3}$三元组，大约有 45 亿种组合。 即使一个微小的常数因素也无法挽救这一点。 

瓶颈来自于显式选择三元组。 中点条件实际上仅取决于一对端点。 一次$A$和$C$固定后，立即确定中点。 

这一观察完全改变了问题。 

我们不选择三个点，而是只选择两个点$A$和$C$。 他们的中点是：$\left(\frac{x_A+x_C}{2}, \frac{y_A+y_C}{2}\right)$如果给定点中存在该中点，那么我们就找到了一个有效的三元组。 

我们可以将所有点存储在哈希集中$O(1)$会员资格检查。 然后我们迭代每对无序的点。 

对于每对：

 1.检查金额是否$x_A+x_C$和$y_A+y_C$是均匀的。 
2. 计算中点坐标。 
3. 检查集合中是否存在该中点。 

这将复杂性降低到$O(n^2)$，很容易满足约束条件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$|$O(1)$| 太慢了 |
 | 最佳|$O(n^2)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 读取所有点并将它们存储在列表中。 
2. 将每个点插入到一个哈希集中。 

该集合允许在检查中点是否存在时进行恒定时间查找。 
3. 将答案初始化为0。 
4. 迭代所有无序点对$(i,j)$在哪里$i < j$。 

使用无序对可以防止重复计算。 这对$(A,C)$应该只处理一次。 
5. 对于当前对，计算：$s_x = x_i + x_j, \quad s_y = y_i + y_j$6.如果有的话$s_x$或者$s_y$很奇怪，跳过这一对。 

整数坐标点不能有小数坐标的中点。 
7. 否则计算中点：$m_x = \frac{s_x}{2}, \quad m_y = \frac{s_y}{2}$8. 检查是否$(m_x,m_y)$存在于点集中。 

如果存在，则将答案加 1。 
9. 打印最终答案。 

### 为什么它有效

 对于每个有效的三元组，恰好有一对无序端点$(A,C)$。 它们的中点是唯一确定的，算法检查输入中是否存在该中点。 

每个有效的三元组都会被计算一次，因为对迭代使用$i < j$。 反向排序$(C,A)$永远不会被重新访问。 

无法计算无效三元组，因为中点条件是使用整数算术精确检查的：$2m_x = x_A + x_C, \quad 2m_y = y_A + y_C$仅当中点与实际输入点匹配时才接受。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    points = []
    point_set = set()
    
    for _ in range(n):
        x, y = map(int, input().split())
        points.append((x, y))
        point_set.add((x, y))
    
    ans = 0
    
    for i in range(n):
        x1, y1 = points[i]
        
        for j in range(i + 1, n):
            x2, y2 = points[j]
            
            sx = x1 + x2
            sy = y1 + y2
            
            if sx % 2 != 0 or sy % 2 != 0:
                continue
            
            mx = sx // 2
            my = sy // 2
            
            if (mx, my) in point_set:
                ans += 1
    
    print(ans)

solve()
```第一部分将所有点读入列表和集合中。 列表保留迭代顺序，而集合提供快速的中点存在检查。 

嵌套循环将每个无序对恰好枚举一次。 使用`j`从`i + 1`避免重复处理并保证正确计数。 

奇偶校验至关重要：```
if sx % 2 != 0 or sy % 2 != 0:
    continue
```如果没有它，整数除法将默默地向下舍入并创建错误的中点匹配。 

仅使用整数算术计算中点。 浮点运算是不必要的，并且会引入可避免的精度问题。 

最终会员资格检查：```
if (mx, my) in point_set:
```是解的几何核心。 如果输入点之间存在中点，则这三个点形成有效的三元组。

 ## 边缘情况

 考虑分数中点情况：```
3
0 0
1 1
2 1
```该算法检查对$(0,0)$和$(1,1)$。 它们的坐标和是$(1,1)$，都是奇数。 由于中点是$(0.5,0.5)$，立即跳过该对。 

接下来它检查$(0,0)$和$(2,1)$。 总和是$(2,1)$。 y 坐标和是奇数，因此也跳过这一对。 

最后一对还产生分数中点坐标。 答案仍然是0。 

现在考虑重复计算的情况：```
3
0 0
1 1
2 2
```唯一有效的三元组使用端点$(0,0)$和$(2,2)$。 该算法处理该对一次，因为它只考虑以下索引：$i < j$。 相反的对永远不会出现，所以答案恰好是 1 而不是 2。 

最后，考虑中点坐标为整数但缺少中点的情况：```
3
0 0
2 2
5 5
```这对$(0,0)$和$(2,2)$产生中点$(1,1)$。 奇偶校验通过，但集合查找失败，因为$(1,1)$不在输入中。 该算法正确地拒绝该对并输出 0。
