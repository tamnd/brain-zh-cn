 ## 解决方案
 ## 问题理解

 蛋糕边框是一系列不同水果的圆形序列。 我们代表鸡蛋果`E`和一个柿子`P`。 一个有效的切片由连续的圆形水果段组成，最多包含`S`水果，并且必须至少含有一种鸡蛋果。 

由于每种水果都是可区分的，因此切片是通过其包含的精确位置集来识别的。 自从`S < n`， 在哪里`n`是水果的数量，每个考虑的切片都是圆的真部分。 因此，选择它的起始位置和长度就唯一地确定了水果的集合，因此我们可以直接计算循环间隔。 官方声明给出`3 <= n <= 10^5`和`1 <= S < n`，时间限制为一秒。 

和`n`一样大`10^5`，检查每个可能长度的每个可能间隔的算法太昂贵了。 在最坏的情况下，有`n(S)`这样的间隔，并且当`S = n - 1`这变成`n(n - 1)`， 关于`10^10`间隔。 即使每个时间间隔的少量恒定工作量也远远超出了一秒的限制所允许的范围。 我们需要一个本质上线性的解决方案。 

圆形性质创造了第一个不明显的边缘情况。 考虑`PEPEP`和`S = 2`。 第一个和最后一个位置相邻，因此两个`P`两端的字符形成两个柿子的一圈。 将字符串视为普通的线性文本会错过由这两个柿子组成的间隔，并会产生错误的答案。 正确答案是`6`。 

全柿子的情况也需要显式处理。 为了`PPPP`和`S = 1`，没有包含鸡蛋果的切片，所以答案是`0`。 假设至少存在一个鸡蛋果的方法可能会错误地访问不存在的鸡蛋果或计算无效的间隔。 

允许的最小切片大小是另一种边界情况。 为了`EPE`和`S = 1`，只允许单片水果。 正是这两个鸡蛋果符合条件，所以答案是`2`。 任何从考虑长度为 2 或更多的间隔开始的方法都会过度计算。 

最后，`S`可能几乎是整个蛋糕。 为了`EPPP`和`S = 3`，所有有效切片都是长度最多为三的适当的圆形间隔。 我们绝对不能数整个圆，因为它的长度是四，`S < n`保证其超出允许范围。 

## 方法

 直接的解决方案可以枚举每个起始位置，并一次延长一个水果的间隔，直到其长度达到`S`。 在扩展时，我们保留是否`E`已经出现，只要满足条件就添加间隔。 这是正确的，因为每个有效切片都有一个起始位置和一个长度`1`和`S`， 和`S < n`防止两种不同的表示描述同一组水果。 

问题是间隔的数量。 正好有`n`每个长度都可能开始，因此暴力方法检查`nS`间隔。 在最坏的情况下，`S = n - 1`, 给予`n(n - 1)`，这大约是`10^10`什么时候`n = 10^5`。 这就是其他简单方法变得无法使用的地方。 

关键的观察结果是，计算不包含`E`。 当区间内的每个水果都是一个时，该区间是无效的`P`。 因此，我们可以从所有可能的长度区间的个数开始`S`并减去全柿区间的数量。 

对于每个长度`1`通过`S`，正好有`n`循环间隔，因为有`n`可能的起始位置。 自从`S < n`，这些区间作为水果组都是不同的。 因此候选切片的总数是`n * S`。 

现在考虑一次最大循环运行`r`连续的`P`水果。 每一个全——`P`间隔必须完全位于这样的一次运行内。 对于固定长度`L`， 在哪里`1 <= L <= r`， 有`r - L + 1`运行内该长度的间隔。 我们只关心长度达到`S`，所以让`k = min(r, S)`。 跑步贡献`(r) + (r - 1) + ... + (r - k + 1)`全部-`P`间隔。 这个算术级数可以计算为`k * (r + 1) - k * (k + 1) / 2`。 

将所有最大贡献相加`P`运行给出无效切片的完整数量。 

唯一的微妙之处是找到圆上的最大游程。 如果字符串的开头和结尾为`P`，这两条直线运行实际上是一条循环运行。 我们可以通过找到任意的来避免特殊的合并逻辑`E`并在那里开始我们的扫描。 一旦扫描开始于`E`， 每一个`P`运行遇到的完全包含在两个之间`E`位置，因此任何运行都不能跨越线性扫描的边界。 

蛮力方法和最优方法可以进行如下比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nS)，最坏情况 O(n²) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取循环字符串`B`，它的长度`n`，以及最大切片大小`S`。 我们首先计算所有可能的真圆间隔，然后删除完全由柿子组成的间隔。 
2. 计算长度区间的总数`1`通过`S`。 对于每个允许的长度有`n`起始位置，所以总数是`n * S`。 
3. 检查字符串中是否包含`E`。 如果没有蛋果，则每个区间都无效，答案立即为零。 
4. 查找任意位置包含`E`并从该位置开始扫描圆。 这有效地旋转了圆弦，而无需实际构造另一个弦。 
5. 保持当前长度`r`连续的`P`跑步。 每当一个`P`遇到，增量`r`。 
6. 每当`E`遇到的话，前面的`P`运行已结束。 放`k = min(r, S)`并减去`k * (r + 1) - k * (k + 1) / 2`从答案中。 然后重置`r`为零。 该公式计算了所有 -`P`可以容纳在本次运行中并且最大长度的间隔`S`。 
7. 毕竟`n`位置已经处理完毕，对最终的位置进行相同的计算`P`跑步。 开始扫描`E`保证最终运行不需要与初始运行合并。 
8. 打印剩余计数。 这些正是包含至少一个的区间`E`并且最多有`S`水果。 

不变的是，处理完每个完成后`P`运行时，答案等于允许的循环间隔总数减去这些已处理运行中包含的每个无效间隔。 最大`P`运行是不相交的，并且每个全`P`间隔恰好属于其中之一，因此不会两次减去无效间隔。 由于每个剩余区间至少包含一个`E`，最终的值正是所需的切片数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_slices(B, S):
    n = len(B)

    # Every length 1..S has exactly n circular intervals.
    ans = n * S

    # If there is no eggfruit, every interval is invalid.
    if 'E' not in B:
        return 0

    # Start at an E so that no P-run crosses the scan boundary.
    start = B.index('E')
    p_run = 0

    for step in range(n):
        c = B[(start + step) % n]

        if c == 'P':
            p_run += 1
        else:
            if p_run:
                k = min(p_run, S)
                invalid = k * (p_run + 1) - k * (k + 1) // 2
                ans -= invalid
                p_run = 0

    # Process the final P-run, if any.
    if p_run:
        k = min(p_run, S)
        invalid = k * (p_run + 1) - k * (k + 1) // 2
        ans -= invalid

    return ans

def solve():
    B = input().strip()
    S = int(input())
    print(count_slices(B, S))

if __name__ == "__main__":
    solve()
```第一个计算，`n * S`，对应于算法的第一部分。 有`n`每个允许长度的间隔以及条件`S < n`意味着这些间隔都不代表整个圆。 

明确的`E`检查处理所有 -`P`循环扫描开始之前的情况。 如果没有它，就没有自然的位置来开始扫描，同时保证边界位于鸡蛋果内部。 

扫描使用模块化索引，`(start + step) % n`，所以它完全访问原始的`n`按循环顺序排列的位置。 我们不需要复制字符串，这使得实现简单并使用恒定的辅助空间。 

当一个`P`运行结束，`p_run`是它的精确长度。 如果跑步有长度`r`， 仅有的`k = min(r, S)`长度可能会产生无效的间隔。 表达式`k * (r + 1) - k * (k + 1) // 2`是`r, r - 1, ..., r - k + 1`。 所有算术都是整数算术。 Python整数具有任意精度，而最大的答案是大约`10^10`，所以不存在溢出问题。 

最终运行在循环之后进行处理。 很容易忽略这一点，因为运行通常是在以下情况下处理的：`E`被发现，但循环扫描可能会在仍在内部时完成`P`跑步。 开始于`E`使最终运行完整，而不是跨越扫描边界分割。

 ## 边缘情况

 圆形边界情况是通过故意在某个位置开始扫描来处理的。`E`。 为了`PEPEP`和`S = 2`，扫描可以从第二个字符开始，产生循环顺序`EPEPP`。 决赛`PP`运行长度为二，因此它有贡献`2 + 1 = 3`无效间隔。 另一个孤立的`P`又贡献了 1 个，在总共 10 个间隔中给出了 4 个无效间隔。 答案是`10 - 4 = 6`。 

全柿子箱在扫描前进行处理。 为了`PPPP`和`S = 1`，没有`E`从中建立扫描边界，更根本的是，每个可能的切片都是无效的。 立即返回零既简单又正确。 

什么时候`S = 1`，每个有效切片都是一个单独的蛋果。 为了`EPE`和`S = 1`，存在三种可能的单例区间，一种是柿子，其余两种是鸡蛋果。 该算法开始于`3 * 1 = 3`并减去其中包含的一个单例`P`运行、生产`2`。 

什么时候`S = n - 1`，该算法仍然只计算适当的间隔。 为了`EPPP`和`S = 3`， 有`4 * 3 = 12`候选区间。 连续三届`P`s 形成一轮，其全部-`P`对于六个无效间隔，间隔为三个长度为一的间隔、两个长度为二的间隔和一个长度为三的间隔。 结果是`12 - 6 = 6`。 

一个`P`跑的时间长于`S`还需要`min(r, S)`截断。 为了`EPPPPE`和`S = 2`，中间的行程长度为四，但不允许长度为三或四的间隔。 对于该运行中的七个无效间隔，只有四个单例间隔和三个长度为二的间隔算作无效。 有`6 * 2 = 12`总候选区间，结果为`12 - 7 = 5`如果该字符串有一个这样的运行。 对于上面的测试用例，两个`E`s 以不同的方式分割字符串，所以实际的运行是`PPPP`直接计算得出`12 - (4 + 3) = 5`; 这正是测试应该使用的原因`EPPPPE`与预期输出`5`， 不是`16`。 

最终测试的更正断言是：```
assert run("EPPPPE\n2\n") == "5", "P run larger than S"
```中心不变量统一处理所有这些情况：每个允许的间隔都从初始总数开始`n * S`，以及每个无效的全`P`通过唯一的最大间隔恰好删除一次`P`运行包含它的程序。
