 ## 解决方案
 ## 问题理解

 我们有一个字符串`S`描述位置 (2,4,6,\ldots,2N) 的公民。 一个角色`H`意味着多项式在该位置必须为正，而`A`意味着它必须是负数。 

我们需要一个具有整数系数和整数根的多项式。 其首项系数必须为 (1) 或 (-1)，并且在满足所需符号的所有多项式中，其次数必须最小。 我们只需要输出度和系数。 

第一个有用的观察是，只有当我们穿过奇数重数的根时，多项式才能改变符号。 考虑 (2i) 和 (2i+2) 处的两个连续公民。 如果所需符号不同，则多项式在开区间 ((2i,2i+2)) 中必须有奇数个根。 

所有根都是整数。 (2i) 和 (2i+2) 之间唯一严格的整数是 (2i+1)。 因此，每当`S[i] != S[i+1]`，多项式必须包含奇重数的根 (2i+1)。 一份就够了，多一份只会提升程度。 

这立即给出了可能的最小程度：

 [
 D=#{i\ne S_{i+1}}。 
]

 我们可以使用这些根构造一个多项式：

 [
 Q(x)=\prod_{S_i\ne S_{i+1}}(x-(2i+1))。 
]

 根恰好出现在需要改变符号的连续公民之间，因此 (Q) 恰好具有所需的符号变化。 我们只需选择使用（Q）还是（-Q），以使第一个公民的符号正确。 

界限 (N\le10^4) 最初可能表明扩展此乘积可能需要 (O(N^2)) 工作，这在 Python 中会很不舒服。 系数界完全改变了情况。 如果多项式的次数至少为 17，则它必须包含至少 17 个所需的正奇根。 17 个这样的根的最小可能乘积是

 [
 3\cdot5\cdot7\cdots35
 =221643095476699771875,
 ]

 它已经大于 (2^{63})。 一元多项式或反多项式的常数系数，直到符号为止，都是其所有根的乘积。 因此，次数为 17 或更高的有效最小次数多项式不能满足系数界限。 

所以每个有效输入都有 (D\le16)。 原始字符串仍然可以包含 10,000 个公民，但扫描后我们最多乘以 16 个线性因子。 

有一些边缘情况很容易被错误处理。 为了`H`，输入是`H`，没有符号变化，常数多项式 (P(x)=1) 是正确的。 总是创建至少一个根的粗心实现将产生非最小多项式。 

为了`A`，输入是`A`，正确的多项式是 (P(x)=-1)。 即使次数为零，也必须从第一个所需符号中选择首项系数。 

为了`HA`，唯一的转换是在位置 2 和 4 之间，因此根必须是 3。多项式 (x-3) 在 2 处为负，在 4 处为正，这与我们需要的相反。 正确答案是```
1
-1 3
```这说明了为什么最终的全局符号不能被忽略。 

为了`AHA`，有两个转变，所以根是 3 和 5。它们的乘积给出

 [
 Q(x)=(x-3)(x-5)=x^2-8x+15。 
]

 在(x=2)，(Q(2)=3>0)，但第一个公民是外星人，所以我们必须对多项式取负并输出```
2
-1 8 -15
```一个粗心的实现，只计算转换但忘记了度数的奇偶性，可能会导致这个符号错误。 

## 方法

 一种直接的方法是识别每一次转变，然后一次扩展相应的产品一个因素。 如果我们忽略系数界限并允许次数增长到 (N-1)，最坏的情况将是长度为 10,000 的交替字符串。 那么就有 9,999 个因数，将它们一一相乘需要

 [
 1+2+\c点+9999
 =\frac{9999\cdot10000}{2}
 =49,995,000
 ]

 系数更新。 对于 Python 解决方案来说，这是不必要的大量工作。 

然而，蛮力构造在数学上是正确的。 每个转换都会在其唯一的整数间隙中产生一个根，并且乘以相应的线性因子会准确地创建这些符号变化。 它的弱点在于它将度数视为潜在的 (O(N))。 

关键的观察结果是系数界可以防止这种情况发生。 由于每个转变都会强制产生一个不同的正奇根，因此 17 次多项式将已经具有一个大小超过 (2^{63}) 的常数系数。 因此，一个有效实例最多可以有 16 个转换。 对输入的扫描仍然需要花费 (O(N))，但多项式构造仅需要 (O(D^2)) (D\le16)。 

这给出了一个非常简单的解决方案。 扫描一次字符串，只要两个相邻字符不同，就收集奇数 (2i+1)，然后乘以因子 (x-r)。 最后根据第一个字符选择整个多项式的符号。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 不使用系数界的朴素扩展 | (O(N^2))，最多 49,995,000 条更新 | (O(N)) | 不必要的缓慢 |
 | 最佳| (O(N+D^2))，其中 (D\le16) | (O(D)) | 已接受 |

 官方竞赛讨论将直接乘法描述为预期的 (O(n^2)) 方法，并指出 (2^{63}) 系数限制有效地使有用度最多为 16。 

## 算法演练

 1. 扫描每一个相邻的对`S[i]`和`S[i+1]`。 如果它们相等，则两个公民之间不需要改变符号，因此那里不需要根。 如果它们不同，则将 (2i+1) 附加到根列表，因为这是严格位于公民位置 (2i) 和 (2i+2) 之间的唯一整数。 
2. 令收集的根的数量为(D)。 这是最小次数，因为每个符号转换都需要至少一个奇重数的根，并且一个根足以执行该转换。 
3. 从多项式（Q(x)=1）开始，由系数列表表示`[1]`。 对于每个根 (r)，将 (Q(x)) 替换为 (Q(x)(x-r))。 如果当前系数按降序存储，则乘以 (x-r) 将根据以下公式更改它们：
 [
 b_j=a_j-r a_{j-1}。 
]
 第一个系数保持 (a_0)，并创建新的最终系数 (-r a_D)。 
4. 确定 (Q) 在第一个公民 (x=2) 处是否已经具有正确的符号。 每个选定的根都大于 2，因此每个因子 (2-r) 都是负数。 因此，
 [
 \运算符名称{符号}(Q(2))=(-1)^D。 
]
 如果第一个字符是`H`，我们需要一个正值。 如果是的话`A`，我们需要一个负值。 当当前符号错误时，对每个系数求负。 
5. 输出 (D) 和所得系数列表。 由于根正是转换点，并且每个根都有重数 1，因此符号在输入字符串更改字符的位置准确地发生变化。 

为什么有效：在两个连续的公民之间恰好存在一个可能的整数根，(2i+1)。 转变于`S`强制该区间内有奇数个根，因此 (2i+1) 至少有一个副本是不可避免的。 我们在那里放了一份副本，给出了最低程度。 每个选定的根恰好位于与该转换相关的两个公民之间，因此穿过它只会翻转多项式的符号一次。 因此，一旦从第一个公民中选择了全局符号，所有相邻的符号都符合所需的模式。 多项式在最终全局符号之前是单调的，并且所有根和系数都是整数，因此满足每个输出要求。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    roots = []

    for i in range(n - 1):
        if s[i] != s[i + 1]:
            roots.append(2 * i + 3)

    degree = len(roots)

    # Coefficients in decreasing order.
    # Initially Q(x) = 1.
    coef = [1]

    for r in roots:
        new_coef = [0] * (len(coef) + 1)

        for j, a in enumerate(coef):
            new_coef[j] += a
            new_coef[j + 1] -= r * a

        coef = new_coef

    # Q(2) has sign (-1)^degree because every root is > 2.
    # We want Q(2) > 0 for H and Q(2) < 0 for A.
    desired_positive = s[0] == 'H'
    q_at_2_positive = (degree % 2 == 0)

    if desired_positive != q_at_2_positive:
        coef = [-x for x in coef]

    print(degree)
    print(*coef)

if __name__ == "__main__":
    solve()
```第一个循环实现了算法演练步骤 1 中的转换检测。使用从零开始的 Python 索引，索引处的公民`i`位置为 (2i+2)，因此公民之间的整数`i`和`i+1`是(2i+3)。 这是一个常见的相差一分的情况。 

多项式乘法以降序存储系数。 如果`coef`代表

 [
 a_0x^k+a_1x^{k-1}+\cdots+a_k,
 ]

 然后乘以 (x-r) 得出

 [
 a_0x^{k+1}
 +(a_1-ra_0)x^k
 +\c点
 +(a_k-ra_{k-1})x
 -ra_k。 
]

 两项任务分别为`new_coef[j]`和`new_coef[j+1]`准确落实这些贡献。 将两个贡献分开还可以避免对第一个和最后一个系数进行任何特殊处理。 

Python 整数不会溢出，因此不需要特殊的 64 位算术。 该问题保证最终系数的幅值低于(2^{63})，并且通过添加正根形成的中间多项式的系数幅值不大于最终乘积的系数幅值。 

最终的符号计算使用每个根至少为 3 的事实。在 (x=2) 处，每个因子 (2-r) 均为负，因此当次数为偶数时，未求反的乘积恰好为正。 如果该标志与第一公民所需的身份不一致，则所有系数都被否定。 

只有一个输入字符串，因此不需要测试用例循环。

 ## 边缘情况

 对于单个公民来说，没有要求更换标志的时间间隔。 有输入`H`，算法找不到根，获得零次，并保持多项式 (1)。 有输入`A`，它同样找到零次但将常数多项式翻转为 (-1)。 不存在转移正是常数多项式最佳的条件。 

对于尽可能最小的转换，请考虑`HA`。 这两个公民分别位于 2 和 4。他们所需的符号不同，因此他们之间必须严格存在奇数个根。 由于唯一的整数为 3，因此最小多项式次数为 1，且根必须为 3。未缩放多项式 (x-3) 在 2 和 4 处具有负号和正号，因此必须对其取负。 结果是(-x+3)。 

对于多次转换，请考虑`AHA`。 所需的变化发生在位置 2 和 4 之间以及位置 4 和 6 之间。算法选择根 3 和 5，产生

 [
 Q(x)=(x-3)(x-5)=x^2-8x+15。 
]

 因为次数是偶数，(Q(2)>0)。 第一个字符是`A`，因此整个多项式被求反：

 [
 P(x)=-x^2+8x-15。 
]

 它在 2、4 和 6 处的值有负号、正号、负号，完全符合要求。 

对于变化很少的大量总体，例如 10,000 个连续的`H`字符，该算法不构造 9999 次多项式。 它扫描整个字符串，找到零个转换，并立即返回 (P(x)=1)。 这说明了为什么输入长度和多项式次数应被视为单独的量。 

最后，考虑一个具有 17 个转换的假设交替串。 这样的输入将强制根至少为 (3,5,\ldots,35)。 它们的乘积已经超过 (2^{63})，因此其最小次数多项式无法满足系数界。 问题的保证排除了这种情况。 这是直接系数乘法是安全的隐藏原因，尽管有规定 (N\le10^4)。
