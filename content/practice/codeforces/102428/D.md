 ## 解决方案
 ## 问题理解

 每一颗星星都有固定的位置`(X, Y)`和一个亮度`B`。 伯尼可能会旋转整个图片，然后打印机从上到下扫描。 自转后，一颗较大的恒星发生了转变`Y`坐标较早打印。 具有相同变形的明星`Y`坐标同时打印。 

旋转必须使每颗较亮的恒星看起来不低于每颗较暗的恒星。 如果星星`i`和`j`有`B_i > B_j`，所需条件为`Y'_i >= Y'_j`。 

旋转中心无关紧要。 用相同的向量平移每颗星会改变每一个变换`Y`相同的量，因此只有新垂直轴的方向很重要。 

我们可以用单位向量来描述该方向`d`。 变换后的点的垂直坐标`p`是它的投影到`d`，即`p · d`。 因此整个问题就变成了寻找方向`d`这样`(p_i - p_j) · d >= 0`对于每一对`B_i > B_j`。 

最多有`1000`星，所以最多可以有`1000 * 999 / 2 = 499500`对。 一个`O(N^2)`算法是现实的，因为这意味着只有大约 50 万对约束。 一个`O(N^3)`方法已经执行了大约十亿个基本操作，而重复检查许多候选旋转的所有对的算法可以达到大约`O(N^4)`而且太大了。 

有几个细节很容易处理不好。 首先，相同的亮度没有订购要求。 例如，```
3
0 0 2
10 0 2
0 10 1
```有答案`Y`。 两颗亮度2星可以打印在一起，合适的方向可以将两者放在亮度1星的上方。 将相等亮度视为需要严格排序的解决方案将错误地拒绝这种情况。 

其次，允许投影的平等。 考虑```
3
1 0 2
-1 0 2
0 0 1
```唯一有用的方向是垂直的。 然后所有三颗星都有相同的变形`Y`，因此两颗较亮的星星与较暗的星星同时打印，这是允许的。 答案是`Y`。 使用严格的`>`而不是`>=`会错误地产生`N`。 

第三，所有恒星可能具有相同的亮度。 例如，```
3
0 0 7
1 2 7
4 -3 7
```有答案`Y`，因为根本没有亮度比较。 任何旋转都是有效的。 

最后，一个点可能位于较亮或较暗点的凸包内部，从而使答案变得不可能。 例如，```
4
0 0 1
2 0 1
0 2 1
1 1 2
```有答案`N`。 亮度 2 星严格位于三颗亮度 1 星形成的三角形内部。 没有线性投影可以使内部点严格高于每个顶点。 仅检查少数邻近恒星的方法可能会忽略这一全局矛盾。 

## 方法

 可以根据约束的几何形状构建直接的强力方法。 每对不同亮度的恒星都给出了一组有效的旋转方向。 所有这些集合的交集正是满足问题的旋转集合。 由于每个约束有两个边界方向，因此可以生成每个边界方向作为候选，并针对它测试每个亮度约束。 如果有`K`相关对，最多有`2K`候选边界，并针对所有约束成本测试一个候选`O(K)`。 和`K = 499500`，这可能需要大约`2K^2`, 接近于`5 * 10^11`检查，这太慢了。 

蛮力在概念上起作用的原因是问题实际上是角度范围的交集。 错误在于从头开始为每个可能的边界重新计算整个交叉点。 

关键的观察是一对恒星不会对旋转给出任意限制。 让星星更明亮`A`，较暗的恒星是`C`，并定义`v = A - C`。 

为了一个方向`d`，更亮的星星打印的时间不低于较暗的星星`v · d >= 0`。 

如果`a`是的角度`v`和`θ`是的角度`d`，这变成了`cos(θ - a) >= 0`。 

因此有效方向形成一个封闭的半圆：`a - π/2 <= θ <= a + π/2`。 

因此，每个亮度约束都是宽度的角度间隔`π`。 

现在的问题是使大约一百万个闭合半圆相交。 可以直接维护路口。 我们保留当前的可行区间，将其展开到实数线上，并为每个新的半圆选择移动了倍数的副本`2π`最接近当前间隔的值。 由于当前可行区间的长度最多为`π`，此副本包含与当前间隔的所有可能重叠。 然后我们将两个普通区间相交。 

这避免了对所有区间端点进行排序，并避免针对每个约束测试每个候选者。 得到的算法是`O(N^2)`时间和`O(1)`除了输入之外的额外空间。 竞赛讨论中还描述了相同的成对角度约束公式。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N^4) | O(N^4) | O(N^2) | O(N^2) | 太慢了|
 | 最佳 | O(N^2) | O(N^2) | O(N) | 已接受 |

 ## 算法演练

 1.读取所有星星并存储它们的坐标和亮度。 坐标足以确定每个几何约束，而亮度告诉我们差异向量必须指向哪个方向。 
2. 检查每对不同的恒星。 如果它们的亮度值相等，则跳过这对，因为任一打印顺序都是允许的。 否则，将这对星从较亮的恒星朝向较暗的恒星定向，并将该向量称为向量`v`。 
3. 计算角度`a = atan2(v_y, v_x)`。 带角度的候选垂直方向`θ`恰好满足该对，当`v · d >= 0`，这相当于`θ`属于闭区间`[a - π/2, a + π/2]`。 
4. 使用第一个非平凡约束来初始化当前可行区间`[L, R]`。 我们故意让这个区间展开，所以它的端点可以在外面`[0, 2π)`。 
5. 对于每个后续约束，考虑其周期性副本`[l + 2kπ, r + 2kπ]`。 选择中心最接近的副本`[L, R]`。 因为当前区间和每个约束区间都最多有长度`π`，任何可以与当前区间相交的副本都必须有一个距离它最近的中心。 将所选副本与`[L, R]`。 
6. 如果新的交集为空，则打印`N`立即地。 不可能存在有效的旋转，因为每个有效方向都必须属于两个区间。 
7. 处理完所有对后，如果可行区间仍然非空，则打印`Y`。 如果所有亮度值都相等，则不会产生约束，因此每个方向都是有效的，我们也打印`Y`。 

### 为什么它有效

 不变的是`[L, R]`精确地表示满足迄今为止处理的每个亮度约束的旋转方向集，其中圆角空间展开到实线上。 

对于一对恒星，不等式`v · d >= 0`恰好是有效方向的一个闭合半圆。 将当前可行集与该半圆相交可以精确地删除违反新对的方向。 选择最近的周期副本不会丢失任何可能的解决方案，因为当前间隔最多有长度`π`，并且只有当两个半圆的圆心最多位于`π`分开。 因此，当存在有效旋转时，在所有约束之后，所维护的间隔是非空的。 

使用闭区间还可以处理旋转后水平对齐的星星。 该语句允许这种相等性，因此必须接受由单个方向组成的可行区间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from math import atan2, pi

def solve():
    input = sys.stdin.readline

    n = int(input())
    stars = [tuple(map(int, input().split())) for _ in range(n)]

    half_pi = pi / 2.0
    two_pi = 2.0 * pi
    eps = 1e-12

    left = None
    right = None

    for i in range(n):
        xi, yi, bi = stars[i]

        for j in range(i):
            xj, yj, bj = stars[j]

            if bi == bj:
                continue

            if bi > bj:
                dx = xi - xj
                dy = yi - yj
            else:
                dx = xj - xi
                dy = yj - yi

            angle = atan2(dy, dx)
            l = angle - half_pi
            r = angle + half_pi

            if left is None:
                left = l
                right = r
                continue

            mid = (left + right) * 0.5

            # Shift the new semicircle by a multiple of 2*pi
            # so that its center is closest to the current interval.
            k = round((mid - angle) / two_pi)
            l += k * two_pi
            r += k * two_pi

            new_left = max(left, l)
            new_right = min(right, r)

            if new_left > new_right + eps:
                print("N")
                return

            left = new_left
            right = new_right

    print("Y")

if __name__ == "__main__":
    solve()
```输入存储为三元组`(x, y, b)`。 嵌套循环只检查每个无序对一次，因此不会意外地重复任何对。 

对于每一对，代码首先忽略相同的亮度。 否则，它会使差异向量从较暗的恒星指向较亮的恒星。 这个方向很重要，因为反转矢量会反转所需的半平面。`atan2`给出该向量的方向. 减法和加法`π/2`给出有效半圆的两个边界. 该间隔有意未标准化为`[0, 2π)`，因为展开的区间更容易相交。 

表达式```
k = round((mid - angle) / two_pi)
```选择中心最接近当前可行区间中心的新区间的周期副本。 蟒蛇`round`精确半整数的行为在这里是无害的，因为两个同样接近的副本中的任何一个都会给出相同的可能边界交集。 

该比较使用了一个很小的 ​​epsilon，因为该算法使用浮点数执行角度算术。 坐标的边界为`10^4`，因此整数差向量的边界为`2 * 10^4`在每个坐标中。 不同的整数方向不能任意接近，容差为`10^-12`安全地小于重要的几何间距。 

Python 中不可能出现整数溢出，而且实际上实现从来不需要大整数运算。 唯一的数值运算是`atan2`、角的加法、除法和比较。

 ## 边缘情况

 ### 同等亮度

 对于```
3
0 0 7
1 2 7
4 -3 7
```每对都有相同的亮度，因此算法会跳过每对。 可行区间仍未设置，这意味着约束系统为空。 算法打印`Y`，正确地将任何旋转视为有效。 

### 同时打印

 对于```
3
1 0 2
-1 0 2
0 0 1
```两颗亮度为 2 的星创建了约束，要求方向同时具有非负和非正`x`成分。 它们的交点正好是垂直方向。 维护的区间最终具有相等的左右端点，而不是变成空的。 算法打印`Y`。 

这种情况对于捕获使用严格比较的实现特别有用。 该问题允许较亮的恒星和较暗的恒星共享相同的变换`Y`。 

### 不可能的内部最大值

 对于```
4
0 0 1
2 0 1
0 2 1
1 1 2
```亮度 2 星位于三颗亮度 1 星形成的三角形内。 每个方向都会投影三角形两个极端投影之间的内点，因此它不能至少与所有三个顶点一样高。 成对的半圆约束有一个空交集，算法最终使得`left > right`，生产`N`。 

### 环绕间隔

 一个区间，例如`[90°,270°]`可能需要表示为`[-270°,-90°]`当当前可行区间接近时`-100°`。 该算法通过添加适当的倍数来处理这个问题`2π`而不是强迫每个间隔进入`[0,2π)`。 如果没有这一步，则有效的交叉路口将穿过`0°/360°`边界可能会被错误地报告为空。
