 ## 解决方案
 ## 问题理解

 我们正在模拟一个人与不同品种的猫反复互动的过程，唯一重要的是每个品种最后一次看到或最后一次互动的顺序。 

每个操作都可以解释为涉及猫品种的请求。 当一个品种再次出现时，我们在概念上指的是该品种之前被处理的最近一次，并且结构必须反映这一演变的历史。 该任务不是关于实体猫本身，而是关于跟踪同一类别重复出现之间的时间关系。 

该过程的输出源自这些交互：处理完整序列后，我们必须能够根据语句注释中描述的模拟规则确定出现了多少个不同品种以及每个品种参与有效“重复交互”的次数。 

典型 Codeforces 介质模拟问题所隐含的约束表明最多大约 2·10^5 事件。 这立即排除了每个查询扫描先前出现的任何二次策略。 在最坏的情况下，简单的 O(n^2) 扫描将涉及多达 10^10 次操作，这在 2 秒的限制下是不可行的。 相反，该结构必须支持每个事件的平均 O(1) 或 O(log n) 更新。 

当同一品种的多次出现与许多其他品种交织时，就会出现微妙的失败案例。 例如，如果序列是 A B C A D A，则正确性取决于始终记住 A 最后一次出现的情况。 仅计算频率而不跟踪新近度的简单方法会错误地同等对待所有 A，并丢失模拟所需的时间结构。 

当所有猫都属于同一品种时，就会出现另一种边缘情况。 在这种情况下，第一个事件之后的每个事件都是重复，并且答案必须反映完全一致的重复引用链，而不是独立计数。 

## 方法

 强力解释维护所有过去事件的列表，并且对于每个新事件，向后扫描以查找同一品种的先前出现的情况。 这很简单：对于每个位置 i，我们搜索 j < i，使得 s[j] = s[i]，取最接近的位置。 如果我们直接模拟，每个步骤可能需要扫描最多 O(n) 个元素，从而产生 O(n^2) 总复杂度。 

这种方法可以正确工作，因为它明确遵循“先前出现”的定义，但是一旦序列增长到超过几千个元素，它就会失败。 

关键的观察是我们根本不需要向后扫描。 对于每个品种，我们只关心它最近出现的情况。 一旦新事件到达，先前发生的事件就变得无关紧要，除了存储的元数据之外。 这将问题转化为维护从品种到上次看到的索引或时间的映射。 

一旦我们维护了这个映射，更新就变成了恒定时间的字典操作。 每次我们看到一个品种时，我们要么初始化它的状态，要么更新它的最后一次出现。 任何派生的统计数据，例如重复次数或总出现次数，也可以增量更新。 

从暴力解决方案到最优​​解决方案的转变本质上是用直接访问缓存状态来取代历史搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力扫描先前发生的情况 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了|
 | 用于上次出现跟踪的哈希图 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们维护一个字典，用于存储每个品种的信息，特别是其最后出现的位置，并可选择计数器其出现的次数。

1. 初始化一个空字典，其中每个键都是一个品种，每个值存储元数据，例如上次看到的索引和频率。 
2. 从左到右迭代事件序列。 
3. 对于每个事件，检查该品种是否已存在于字典中。 
4. 如果不存在，则用当前位置初始化其记录，并将其计数设置为 1。 
5. 如果确实存在，则将其最后出现的位置更新为当前索引并增加其计数。 
6. 或者，如果问题需要仅计算“有效重复”，则在第二次或更多次看到某个品种时更新全局计数器。 
7. 处理完所有事件后，汇总字典中的结果，例如不同品种的数量或每个品种的计数。 

关键思想是每个事件仅修改一个品种的状态，并且没有事件需要比先前存储的状态更多的知识。 

### 为什么它有效

 在每一步中，字典都会将每个品种的完整相关历史记录压缩为一个状态：其最近的位置以及出现的次数。 任何涉及该品种的未来事件仅取决于此存储状态，而不取决于任何早期发生的事件。 这创建了一个不变量，即字典始终准确地反映所有已处理事件的效果，并且不需要额外的历史信息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = input().split()

    last_pos = {}
    freq = {}

    repeat_count = 0

    for i, c in enumerate(a):
        if c in freq:
            freq[c] += 1
            repeat_count += 1
            last_pos[c] = i
        else:
            freq[c] = 1
            last_pos[c] = i

    distinct = len(freq)

    print(distinct, repeat_count)

if __name__ == "__main__":
    solve()
```字典`freq`跟踪每个品种出现的次数，同时`last_pos`存储最新的索引。 在此实现中，通过递增来捕获核心模拟要求`repeat_count`每当一个品种出现多次时。 最终输出并不严格需要索引本身，但包含索引是为了反映语句中描述的时间结构。 

主要的微妙之处是确保重复计数器在第一次出现后的每次出现时增加，而不仅仅是在第二次出现时增加。 另一个常见错误是忘记重置或错误地重新初始化测试用例之间的字典条目，这会破坏模拟状态。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个事件执行 O(1) 字典操作 |
 | 空间| O(k) | k 是存储在字典中的不同品种的数量 |

 该解决方案随事件数量线性扩展，完全符合最多 200,000 次操作的典型限制。 内存使用量仅与不同品种成正比，而不是与总事件成正比，这可以防止在具有长重复序列的情况下发生爆炸。

 ## 边缘情况

 一种重要的边缘情况是只有一个品种重复多次。 用于输入`A A A A A`，字典会增长到大小一，但重复计数器必须在第一步之后的每一步中增加。 状态演变为 freq[A] = 5 和 Repeat = 4，算法会自然地处理这种情况，因为它会在每次现有按键点击时增加计数器。 

另一种情况是所有元素都不同，例如`A B C D`。 字典大小增加到四并且不会出现重复增量。 如果没有正确命中字典，则重复计数为零，无需任何特殊处理即可匹配期望。 

混合交错情况如`A B A C B A`强调正确维护每个键的独立计数器。 每次查找仅涉及一个条目，因此之前出现的其他品种不会造成干扰。 最终状态保持一致，因为每个品种的频率在相同的共享结构中独立进化。
