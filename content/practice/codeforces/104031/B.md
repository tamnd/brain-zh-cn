 ## 解决方案
 ## 问题理解

 两个学生相继解决一系列问题。 Kesha 在每个问题上花费固定的时间，称之为$t_k$，并且 Melentiy 花费$t_m$。 他们都在同一时刻开始并持续工作，直到一个称为“散步”的决定时刻。 

这个决定时刻有两种发生方式。 第一种情况是两个学生碰巧同时完成一个问题。 由于每个完成都会定期发生，因此这些同时完成会以其步骤时间的公倍数发生。 第二个是当其中一个人完成所有任务时$n$问题，之后交互发生变化：完成的学生在自己的每个完成时刻有效地“呼吁”休息，而其他学生只能在自己的完成时间做出回应。 这会造成延迟，直到下一刻与速度较慢的学生的日程安排保持一致。 

任务是计算步行开始的最早时刻，然后确定到那时每个学生已经完成了多少个问题，上限为$n$。 

输入由三个整数组成：问题数$n$，以及每个问题的时间$t_k$和$t_m$。 输出是两个整数，表示步行开始时 Kesha 和 Melentiy 解决了多少问题。 

尽管这个过程听起来是动态的，但一切都完全由周期性结构决定。 每个学生的进步在时间上都是线性的，因此任何有效的答案都必须来自一小组候选时间戳：基于最小公倍数的同步时刻，以及一个学生达到时的边界调整时刻$n$问题，另一个在下一个兼容完成时做出反应。 

简单的模拟会随着时间的推移逐步增加两个计数器，直到满足停止条件。 这种方法太慢了，因为事件数量最多$n$可以达到$10^9$或更多。 

当一名学生在任何同步发生之前完成所有问题时，就会出现边缘情况。 例如，如果$t_k \ll t_m$，凯莎可能会完成所有$n$早在 Melentiy 完成共享边界的足够工作之前就已经出现了问题。 天真的“第一公倍数”方法会忽略这一点，并错误地将答案推到太远的未来。 另一个边缘情况是当$t_k = t_m$，其中每一步都会发生同步，但上限为$n$仍须强制执行。 

## 方法

 直接模拟将时间视为离散的，并重复前进到任一学生的下一个完成事件。 每一步都会将时间增加到下一个倍数$t_k$或者$t_m$，并检查是否满足步行的两个条件。 这是正确的，因为它反映了真实的过程，但到达答案之前的事件数量可以与$n$，并且每次转换都是持续的工作，这使得对于大的约束而言速度太慢。 

关键的结构观察是系统是周期性的。 忽略限制$n$，两个学生同时完成问题的唯一次数是$\mathrm{lcm}(t_k, t_m)$。 这将无限的交互减少为简单的算术级数。 然而，有限上限$n$引入截断：在时间之后$n \cdot t_k$或者$n \cdot t_m$，学生停止进步，这打破了纯粹的周期性。 

因此，解决方案变成了两种制度的组合。 在任何一个学生完成所有问题之前，答案必须是以下的倍数$\mathrm{lcm}(t_k, t_m)$。 一名学生完成后，通过将另一名学生的完成网格与较快学生的完成时间对齐来确定答案。 我们评估这两种制度并采取最早的有效时刻。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 模拟 |$O(n)$|$O(1)$| 太慢了|
 | 算术（LCM + 边界对齐）|$O(\log \min(t_k,t_m))$|$O(1)$| 已接受 |

 ## 算法演练

 我们从两个独立的机制构建候选时刻并选择最早的一个。 

1. 计算最小公倍数$t_k$和$t_m$。 这代表了两个学生在无限过程中同时完成问题的基本周期。 我们使用gcd关系得到它$\mathrm{lcm}(a,b) = a \cdot b / \gcd(a,b)$。 
2. 计算Kesha完成所有问题的时间，即$T_k = n \cdot t_k$，并且类似地$T_m = n \cdot t_m$。 这些是周期性行为发生变化的截断点。 
3. 在任一完成之前考虑同步事件。 最早有意义的同步是最小的倍数$\mathrm{lcm}(t_k, t_m)$这至少是零时间，但如果我们想要纯粹的周期性行为，我们只保留两个学生到达最终问题之前发生的那些时刻。 在实践中，我们将第一个候选视为 lcm 的第一个倍数，然后判断它是否位于有效求解窗口内。 
4. 处理Kesha先完成的情况，意思是$T_k \le T_m$。 时$T_k$，凯莎可能已经在等待了。 Melentiy 只能在他自己的完成时间做出响应，因此实际会议会以最小的倍数发生$t_m$大于或等于$T_k$。 
5. 通过将 Kesha 的完成网格对齐来对称地处理 Melentiy 首先完成的情况$T_m$。 
6. 比较所有候选时间：最佳同步时间和两个边界驱动时间，并选择最小的。 
7.最后一次$T$确定后，计算每个学生解决的问题数：$\min(n, T // t_k)$和$\min(n, T // t_m)$。 

### 为什么它有效

 每个可能的行走时刻必须与至少一个学生完成问题的时间一致，因为状态仅在完成边界处发生变化。 在任何一个学生完成所有任务之前$n$问题，同时完成的情况正是由 LCM 的倍数来表征的。 当一名学生停止进步后，系统会缩减为单个算术网格，下一个可行的交互是结束时刻后该网格上的下一个倍数。 这耗尽了所有结构上不同的情况，因此不存在其他候选时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import math

def solve():
    n, tk, tm = map(int, input().split())

    def lcm(a, b):
        return a // math.gcd(a, b) * b

    L = lcm(tk, tm)

    Tk = n * tk
    Tm = n * tm

    # candidate 1: first synchronization after start, but capped by both still running
    t_sync = L

    # candidate 2: Kesha finishes first, align to tm
    t_k = ((Tk + tm - 1) // tm) * tm

    # candidate 3: Melentiy finishes first, align to tk
    t_m = ((Tm + tk - 1) // tk) * tk

    t = min(t_sync, t_k, t_m)

    print(min(n, t // tk), min(n, t // tm))

if __name__ == "__main__":
    solve()
```该代码首先计算 LCM，它是所有联合完成行为的支柱。 然后，它会计算两个学生到达终点时的确切完成时间$n$- 第一个问题。 

表达式`((Tk + tm - 1) // tm) * tm`和它的对称对应物在另一个学生的完成网格上实现天花板划分。 这是离散对齐步骤，模拟“等待下一个可解决的问题边界”。 

最后，答案时间是同步和边界对齐候选者中的最小值，并且解决问题的数量通过整数除法得出，上限为$n$。 

一个微妙的细节是，即使一个学生更快，也必须考虑所有候选时间，因为完成之前的同步仍然可能早于基于完成的事件。 

## 工作示例

 ### 示例 1

 让$n = 3$,$t_k = 2$,$t_m = 3$。 

2 和 3 的 LCM 是 6。因此联合完成发生在时间 6。 

Kesha 在时间 6 完成，Melentiy 在时间 9 完成。 

现在我们计算边界对齐。 Kesha 以 6 结束，Melentiy 可以以 6 响应，因为 6 可被 3 整除。所以$t_k = 6$。 同样，Melentiy 的成绩为 9，Kesha 的成绩为 10？ 实际上9之后的下一个2的倍数是10，所以$t_m = 10$。 

我们至少取 6、6、10，给出$T = 6$。 

| 时间候选| 价值|
 | ---| ---|
 | 液晶模组同步| 6 |
 | 凯莎完成对准| 6 |
 | Melentiy 完成对准 | 10 | 10
 | 决赛| 6 |

 在第 6 时刻，Kesha 解决了$6 // 2 = 3$问题和 Melentiy 已经解决$6 // 3 = 2$。 

### 示例 2

 让$n = 4$,$t_k = 1$,$t_m = 5$。 

LCM 为 5。同步候选者为 5。 

Kesha 获得 4 分，Melentiy 获得 20 分。 

当 Kesha 完成 4 后，下一个 5 的倍数是 5。 

所以候选人是 5、5 和 20，最终时间为 5。 

| 时间候选| 价值|
 | ---| ---|
 | 液晶模组同步| 5 |
 | 凯莎完成对准| 5 |
 | Melentiy 完成对准 | 20 |
 | 决赛| 5 |

 在第 5 时刻，Kesha 解决了 4 个问题（上限为 n），Melentiy 解决了 1 个问题。 

这些例子表明，即使同步很早就存在，边界效应也不会覆盖它，除非它们产生更小的可行会议时间。

 ## 边缘情况

 当$t_k = t_m$，每个时刻都是一个同步点，但答案仍然受到约束$n$。 该算法处理此问题是因为 LCM 等于步骤本身，并且两个边界对齐也解析为不超过自然完成时间的倍数，因此最小值始终一致。 

例如，当一名学生速度更快时$t_k = 1$和$t_m = 10^9$，凯莎极早地解决了所有问题。 该算法正确地切换到“先完成”机制，其中 Melentiy 的下一个倍数决定了交互，而不是错误地依赖于 LCM 同步，因为 LCM 同步发生得太晚了。 

什么时候$n = 1$，两个学生都有效地完成了第一步，并且所有候选人都崩溃到最小的$t_k$,$t_m$， 和$\mathrm{lcm}(t_k, t_m)$。 该实现仍然可以正确运行，因为所有公式都可以干净地简化为第一步比较，而无需特殊的大小写。
