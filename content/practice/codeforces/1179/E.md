 ## 解决方案
 ## 问题理解

 我们正在处理几个函数，它们的行为就像一个巨大的整数行上的单调步进计数器。 每个函数从位置 0 处的值 0 开始，在位置 10^18 处以固定值 L 结束，并且只能以非常有限的方式更改：当我们从 x−1 移动到 x 时，该值要么保持不变，要么只增加 1。 

这意味着每个函数本质上都是放置在整数行某处的 L 个“跳转”的隐藏序列。 在跳转之间，函数是平坦的； 跳跃时，它增加一。 每个函数的整个结构由这 L 个跳转点所在的位置决定。 

任务是在数轴上为每个函数 i 分配一个区间 [l_i, r_i]，使得在该区间内函数至少增加 L/n。 同时，这些间隔在不同功能之间不得重叠，除非可能在端点处接触。 

交互模型允许查询 f_i(x) 的任何函数和位置，但查询数量有限，因此重建所有 L 个跳转位置通常是不可能的。 

这些约束迫使我们采用每个查询对数的策略。 由于 n 可以高达 1000 并且 L 可以非常大，因此任何尝试扫描或重建全功能配置文件的解决方案都会立即被排除。 即使是每个函数的二分搜索方法也必须仔细控制以保持在 2⋅10^5 查询预算之内。 

如果尝试为每个函数独立分配间隔而不协调它们在 x 轴上的位置，就会出现一种微妙的失败情况。 即使每个区间单独捕获足够的增长，它们也可能在 x 上重叠，这是禁止的。 因此，核心困难不仅在于找到足够的增长区间，还在于将它们置于全局不重叠的顺序中。 

## 方法

 蛮力思想在概念上很简单：对于每个函数，通过重复查找函数增加的下一个点来定位其所有跳跃位置，从而有效地重建所有 L 增量。 一旦知道了完整的结构，人们就可以沿着 x 轴贪婪地切出连续的片段。 这是可行的，因为每个函数完全由其跳转集决定，因此显式重构使问题变得微不足道。 

问题是成本。 每次跳转都需要在最多 10^18 的范围内进行二分搜索，大约需要 60 次查询。 每个函数执行 L 次是不可能的，因为 L 可能非常巨大，甚至只对所有函数执行 L 次总跳转也远远超出了限制。 

关键的观察是我们不需要完全重建。 对于每个函数，我们只需要找到一个阈值点，从某个起始位置开始累积 L/n 的增量。 因为该函数是单调的，具有单位步长，所以这简化为经典的“第 k 个 1 位置”查询问题：我们可以二分搜索最小的 x，其中 f_i(x) ≥ target。 

这让我们可以将每个函数压缩为单个关键坐标。 一旦每个函数贡献一个这样的坐标，问题中的存在保证就确保这些坐标可以被排序为有效的非重叠分割。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 全面重建所有跳跃| O(n·L·log 10^18) | O(n·L·log 10^18) | O(Ln) | 太慢了 |
 | 每个函数对阈值进行二分搜索 | O(n log 10^18) | O(n log 10^18) | O(n) | 已接受 |

 ## 算法演练

 我们将每个函数简化为一个关键位置：它累积 L/n 的最早点从零开始增加。

1. 对于每个函数 i，我们计算目标值 T = L/n。 这是我们想要在其间隔内捕获的增量数。 
2. 对于每个函数 i，我们在 [0, 10^18] 范围内对 x 进行二分搜索，以找到满足 f_i(r_i) ≥ T 的最小位置 r_i。每次检查都使用对交互器的查询。 
3.计算完所有r_i后，我们按r_i升序对函数进行排序。 这给出了每个函数“达到”其所需增量质量的顺序。 
4. 我们按此排序顺序构造区间。 我们将第一个间隔设置为从 0 开始。下一个间隔从前一个间隔开始。 对于排序顺序中的第 i 个函数，我们将其区间指定为 [current_left, r_i]，然后更新 current_left = r_i。 
5. 输出所有构造的区间。 

关键的非显而易见的步骤是按 r_i 排序。 如果没有排序，间隔将任意重叠。 排序结构强制对数轴进行一致的从左到右的分解。 

它之所以有效，与单调性有关。 每个函数只会增加，因此一旦它累积 T 增量到某个点 r_i，它就永远不会失去进度。 排序的端点确保较早的间隔不晚于较晚的间隔结束，从而可以按该顺序分配不相交的段，同时保留每个段内所需的增量阈值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(i, x):
    print("?", i, x)
    sys.stdout.flush()
    return int(input().strip())

def solve():
    n, L = map(int, input().split())
    need = L // n

    r = []

    for i in range(1, n + 1):
        lo, hi = 0, 10**18
        while lo < hi:
            mid = (lo + hi) // 2
            val = ask(i, mid)
            if val >= need:
                hi = mid
            else:
                lo = mid + 1
        r.append((lo, i))

    r.sort()

    ans = []
    cur = 0
    for pos, i in r:
        ans.append((i, cur, pos))
        cur = pos

    print("!")
    for i, l, rr in ans:
        print(l, rr)

if __name__ == "__main__":
    solve()
```该代码依赖于每个函数的标准二进制搜索。 每个查询都要求中点处的函数值，并且我们缩小搜索间隔，直到隔离出函数达到所需阈值的第一个位置。 然后，排序步骤将独立阈值转换为全局一致的分区。 

一个微妙的部分是，输出是在排序后构建的，但我们仍然需要根据原始函数索引进行输出。 决赛`ans`list 存储映射回函数 ID，同时保留构造的段顺序。 

## 工作示例

 考虑一个简单的情况，其中 n = 3 且 L = 3，因此 need = 1。每个函数在不同的未知点处恰好增加 1。 

我们对每个函数进行二分查找以找到其第一个增量位置。 

| 功能| 二分查找结果 r_i |
 | ---| ---|
 | 1 | 5 |
 | 2 | 2 |
 | 3 | 8 |

 排序后我们得到顺序：函数2、函数1、函数3。 

我们分配间隔：

 | 步骤| 功能| 间隔 | 当前左|
 | ---| ---| ---| ---|
 | 1 | 2 | [0, 2] | 2 |
 | 2 | 1 | [2, 5] | 5 |
 | 3 | 3 | [5, 8] | 8 |

 每个区间通过构建 r_i 来捕获其函数的至少一个增量，因为 r_i 被定义为函数达到所需阈值的第一个点。 

现在考虑一个函数在其增长过程中交错的情况。 即使一个函数增长较早而另一个函数增长较晚，排序也可确保较早增长的函数获得较早的段，从而防止重叠违规。

 ## 边缘情况

 当 n = 1 时，整个区间必须分配给单个函数。 算法仍然对第L个增量位置进行二分查找，得到的区间自然就变成了[0,r_1]，有效。 

当功能相同时，所有 r_i 值都一致。 然后排序会产生任意顺序，但由于所有端点都相等，因此构造的链退化为没有重叠的接触段，这是端点条件所允许的。 

当 L/n = 1 时，每个函数在其段内只需要一个增量。 然后，二分搜索找到每个函数的第一个跳转位置，并且分段简化为沿轴对这些第一个跳转进行排序。
