 ## 解决方案
 ## 问题理解

 我们有一个起始数字和两个交替“分解”它的玩家。 仅当当前数字可以写为两个严格较小的正整数的 XOR 时，才可能进行移动。 如果存在这样的分割，则主动玩家选择有效的分割，然后对手选择两个结果数字之一作为下一个状态。 

从爱丽丝的角度来看，这是一个零和游戏，她想迫使对手无法进行任何有效的异或分裂。 每一步都会将当前的数字减少到一个更小的数字，但对手的选择使路径变得对抗。 

交互约束将 Alice 的分裂次数限制为 63，这强烈暗示状态演化与二进制长度相关，因为任何高达 10^18 的数字最多有 60 位。 

一个关键的结构事实是，除非数字至少有两个设置位，否则无法通过 XOR 拆分数字。 如果一个数是 2 的幂，或者等于 1，那么它就是终结数。 更一般地说，如果一个数字有 k 个设置位，我们可以考虑在达到最终状态之前可以执行多少“安全减少”。 

边缘案例的数量非常少。 如果n等于1，Alice就根本无动于衷，必须立即接受失败。 对于 n 等于 8 等 2 的幂，任何有效的 XOR 分解都会强制两个部分共享相同的最高位结构，这仍然可以减少问题，但限制分支选项。 

微妙之处在于鲍勃总是为爱丽丝选择最差的分支。 因此，任何策略都必须确保每次分裂的两个孩子都以受控的方式“逐渐变弱”。 

## 方法

 蛮力视角是模拟博弈树。 从状态 p，枚举所有有效的 XOR 分解 p1、p2，然后假设对手选择最差的子级并继续递归。 这形成了一个最大数为 10^18 的极小极大树。 尽管每个数字的分解次数有限，但分支很大并且深度可以达到 60。由于不同的 XOR 拆分会产生不相关的位模式，因此可达状态的数量会爆炸。 这是不可能的。 

关键的观察结果是 XOR 分裂在位上表现出线性：每次分裂对应于将 p 的集合位分布到两个不相交的子集中。 因此，任何有效的移动本质上都是将 p 的集合位划分为两个非空组，而下一个状态是这些子集 XOR 之一。 这将游戏重新构建为重复分区位掩码。 

获胜的想法是始终创建一个分裂，使一个孩子保持为单个设置位或一个非常受控的结构，迫使鲍勃进入一种状态，他的选择很快就会崩溃位计数。 通过精心构造，Alice 可以确保每次移动都以受控方式减少设置位总数，并保证在 63 次移动内终止。 

标准的建设性策略是重复隔离最低设置位，迫使 Bob 最终留下 2 的幂或 0-1 结构，其中不可能进一步分裂。

 ## 算法演练

 我们将该数字解释为位掩码。 中心目标是反复减少设置位的数量，直到只剩下一个位。

1. 如果n为1，则立即选择第二个玩家，因为根本不存在任何动作，第一个玩家立即失败。 
2. 否则，Alice 先玩。 这是因为任何大于 1 的 n 都至少有一个有效的 XOR 分解。 
3. 在当前 p 的每一轮中，找到最低设置位，表示为 b。 这种位隔离很重要，因为它提供了保证异或正确性的正分割。 
4. 通过从 p 中删除位 b 来构造伙伴编号 q，即 q = p XOR b。 这保证了 q < p 且 q > 0。 
5. 将移动设置为 (b, q)。 这始终有效，因为 b XOR q 等于 p，并且两者均为正且严格小于 p。 
6. Bob 选择 b 或 q 后，下一个状态就是他选择的那一边。 如果他选择 b，状态就会变成 2 的一次幂，这是终结状态。 如果他选择 q，则设置位数会严格减少，因为一位已从考虑中永久删除。 
7. 重复此过程直至终止。 由于每一步要么结束游戏，要么减少设置的位数，而初始位数最多为 60 位，因此该过程在 63 步内完成。 

### 为什么它有效

 不变的是，每次移动之后，当前状态下的设置位总数沿着对手避免立即终止的任何路径严格减少。 由于 Bob 总是选择两个 XOR 部分之一，并且其中之一始终是单位数，因此 Alice 确保至少一个分支立即崩溃，而另一个分支降低了位复杂性。 这保证了无论鲍勃如何玩，游戏都不能无限期地继续下去，并且必须在允许的 63 步以内终止。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        if n == 1:
            print("second")
            continue

        print("first")
        sys.stdout.flush()

        p = n

        for _ in range(63):
            if p == 0:
                break

            b = p & -p
            q = p ^ b

            print(b, q)
            sys.stdout.flush()

            a, b2 = map(int, input().split())

            if a == 0 and b2 == 0:
                break

            if a == b:
                p = b
            else:
                p = q

if __name__ == "__main__":
    solve()
```该程序首先处理简单的失败位置 n 等于 1。对于任何更大的值，它承诺首先玩。 所选择的移动始终隔离最低有效设置位，确保有效的异或分解。 读取 Bob 的选择后，状态将更新为 Bob 选择的分支。 

一个微妙的实现细节是使用`p & -p`有效地提取最低设置位。 另一个是确保每次输出后刷新，因为交互取决于立即响应。

 ## 边缘情况

 对于 n = 1，算法立即选择第二个并且不执行任何操作，因为不存在 XOR 分解。 

对于n = 2（二进制为10），唯一的分割是（2 XOR 0），由于正性约束，这是无效的，因此游戏在第一个决定后立即结束。 

对于 n 是 2 的幂，每个有效的分割都会强制形成一种结构，其中一个分支立即成为终端，因此对手无法将游戏延长到超过一两步，这与最低设置位策略快速崩溃状态空间的不变量一致。
