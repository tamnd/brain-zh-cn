 ## 解决方案
 ## 问题理解

 我们从一个整数状态开始，最初等于`n`。 更改它的唯一方法是通过使用辅助值的受约束“中断”操作`y`。 我们一步选择一个数字`y`严格之间`0`和当前值`x`，并且我们还要求`x XOR y`为正且仍严格小于`x`。 选择了这样一个之后`y`，我们可以替换`x`与任一`y`或者`x XOR y`。 

任务是确定我们是否可以从`n`降至目标值`m`最多使用 63 个这样的操作，如果是这样，则显式构造一个有效的中间值序列`x`。 

约束很大，最多 10^18 和 10^4 测试用例，这会立即排除对以下值进行任何状态图搜索`x`。 每个有效状态最多有 2 个转换`y`，并且分支因子基本上是线性的`x`，因此任何状态上的 BFS 或 DP 都是不可能的。 

不明显的困难是并非每对`(x, y)`是可用的。 条件`x XOR y < x`严格限制哪些位`y`允许相对于`x`。 一种常见的失败模式是假设我们总是可以“选择一些`x`并减少它”，当 XOR 中的进位增加较高位时，这是错误的。

 声明中已经有一个显示不可能性结构的小例子：`n = 4, m = 2`。 从`100₂`， 每一个`y < 4`产生`x XOR y >= 4`，因此不存在有效的第一步。 这表明即使在以下情况下操作也可能完全卡住：`m < n`。 

## 方法

 暴力视图对待每个值`x`作为有向图中的节点。 对于每个有效的`y`，我们生成最多两个传出边：`y`并到`x XOR y`。 然后我们搜索一条路径`n`到`m`。 这在原则上是正确的，但完全不可行。 即使是为了`x`大约10^18，候选人数量`y`是线性的`x`，即使探索一小部分也超出了任何限制。 

关键的观察结果是该操作实际上并不是任意 XOR 转换。 约束条件`x XOR y < x`力量`y`尊重最高设置位`x`。 具体来说，我们必须避免以增加高位的方式将该位从 1 翻转到 0，否则 XOR 结果会跳到上面`x`。 

这个限制意味着一个结构性属性：我们不能随意减少`x`，但我们可以安全地将其减少到严格包含在其位结构内的值。 特别是，如果我们选择`y`这样它只使用已经存在于中的位`x`， 然后`x XOR y`删除这些位而不引入新的更高位。 这提供了受控的位清除行为。 

第二个关键思想是将过程视为对之间差异的位操作`n`和`m`。 而不是直接强行`x`朝向`m`，我们逐渐“过滤掉”一些`x`直到我们能够安全着陆`m`。 一个建设性的策略出现了：我们反复转向精心选择的中间状态，这些状态在缩小活动位掩码的同时保持有效性。`x`。 

已知的解决方案通过逐步消除当前之间的最高不同位来构建序列。`x`和目标`m`，确保每一步都是有效的中断操作。 因为我们总是可以通过 XOR 与精心选择的子掩码引入中间状态，所以我们可以保证达到`m`最多 63 个步骤，匹配位长度限制。

 ## 算法演练

 我们维持当前价值`x`，从`n`，并构建状态序列。 

1.如果`x == m`，我们立即停止，因为我们已经到达目标。 
2.找到最高位在哪里`x`和`m`不同。 让这一点成为`p`。 
3. 构造一个值`y`严格小于`x`并仅使用设置的位`x`但不能处于违反约束的位置。 目标是使`x XOR y`严格减少最高不同位，同时保持结果低于`x`。 
4. 执行操作`x = x XOR y`。 选择此选项是因为 XOR 干净地删除了选定的位，而不会引入类似进位的增长。 
5. 追加新的`x`到顺序。 
6. 重复直到`x == m`或者我们到达 63 步。 

步骤3中的关键构造是选择`y`作为子掩码`x`其目标是最高活动位`x`同时保持合法性。 这确保了`x XOR y`严格小于`x`，因为我们删除了最高有效 1 位`x`无需引入新的更高位。 

### 为什么它有效

 不变的是每一步都严格减少当前的最高设置位`x`，或者保留它，同时以受控方式减少位计数，以保证最终消除所有不与`m`。 由于 XOR 仅翻转位，并且我们始终确保不引入更高位，因此该序列在字典位重要性方面严格递减。 由于整数受到 60 位表示形式的限制，因此我们必须在最多 63 次归约内终止。 

此外，每一步都保持可达性，因为我们只选择`y`使得两者`y < x`和`x XOR y < x`，保证操作定义的有效性。 该结构确保我们永远不会通过仅对现有的设置位进行操作来违反这些约束`x`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def highest_bit(x):
    return x.bit_length() - 1

def solve_one(n, m):
    if n == m:
        return [n]

    path = [n]
    x = n

    for _ in range(63):
        if x == m:
            break

        # find highest bit where x differs from m
        diff = x ^ m
        p = diff.bit_length() - 1

        # try to construct a y that clears this bit in x safely
        # take lowest set bit under constraint: use a single bit in x
        # at position p if possible, otherwise fallback to lowest set bit
        if (x >> p) & 1:
            y = 1 << p
        else:
            y = x & -x

        # ensure y < x
        if y == x:
            y = x & (x - 1)

        nx = x ^ y

        # safety adjustment: ensure valid transition
        if not (0 < y < x and 0 < nx < x):
            # fallback: remove lowest set bit
            y = x & -x
            nx = x ^ y

        path.append(nx)
        x = nx

    if x != m:
        return None
    return path

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        res = solve_one(n, m)
        if res is None:
            out.append("-1")
        else:
            out.append(str(len(res) - 1))
            out.append(" ".join(map(str, res)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该实现保留了显式的值路径，因此可以直接重建输出。 每次迭代都会选择一个位来使用 XOR 和单个二次幂掩码来删除。 这是最简单的安全结构，因为删除一组位可以保证`y < x`并确保`x XOR y < x`只要我们通过后备避免无效的情况。 

回退逻辑是必要的，因为在严格约束下直接选择最高的不同位并不总是安全的； 回落到最低设置位可以保证进度，同时保持有效性。

 ## 边缘情况

 最重要的边缘情况是当`x`是二的幂。 在这种情况下，任何有效的`y`必须等于该位或更小的数字，并且大多数选择违反`x XOR y < x`。 回退到最低设置位保证我们仍然可以减少`x`安全地不增加它或打破限制。 

另一种边缘情况发生在`x`和`m`仅低位不同，而共享高位。 Directly targeting the highest differing bit can temporarily violate the constraint, so the fallback ensures legality while still making progress toward the target.

 Finally, when`x`有许多设置位，激进的异或选择可能会意外地产生大于的中间值`x`。 基于不变的回退到单位删除可以防止任何此类升级，确保单调下降`m`。
