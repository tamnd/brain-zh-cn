 ## 解决方案
 ## 问题理解

 我们得到一组固定的硬币面额：1、3、6、10 和 15。对于每个查询，我们必须使用任意数量的这些硬币构建精确的总值 n，目标是最大限度地减少使用的硬币数量。 

这里的关键结构是硬币类型是固定的并且数量非常少，但是n可以非常大，高达10亿。 这立即表明枚举组合或在 n 上进行任何基于状态的动态编程是不可能的。 解决方案必须在恒定或非常小的摊余时间内计算每个测试用例的答案。 

天真的阅读可能会表明这类似于最短路径或背包式最小化问题。 然而，对硬币价值及其具体结构的限制强烈建议采用贪婪或有界分解方法。 

一个微妙的边缘情况是，如果硬币系统不规范，纯粹基于最大硬币的贪婪策略可能会失败。 例如，对于 1、3、4 这样的硬币，贪婪对于 6 会失败（4+1+1 与 3+3）。 因此，我们不能假设贪婪是毫无道理的。 我们必须依靠三角数的特殊结构。 

另一种边缘情况是 n 值较小，其中最佳组合可能会混合许多小硬币而不是一个大硬币。 例如，n = 2 不能使用任何大于 1 的硬币，因此它必须回落到两个 1 硬币。 任何策略都必须正确处理这些低值，而不假设有更大面额的可用。 

## 方法

 暴力方法会将其视为经典的无界背包：对于每个 n，计算 dp[x] 作为形成总和 x 所需的最小硬币数量。 这需要转换五种硬币类型，每个测试用例的复杂度为 O(n)。 对于 n 高达 1e9 和高达 1e4 的测试用例，这在时间和内存上都是完全不可行的。 

我们需要不同的视角。 关键的观察结果是，这套硬币非常小且结构严密。 最大的硬币是 15 枚，所有硬币都是倍数或组合，范围很窄。 这表明，对于较大的 n，解决方案将通过使用尽可能多的 15 个硬币来主导，只有少量的剩余部分可以得到最佳处理。 

这导致了有界残基策略。 任何最优解都可以写成：

 n = 15k + r，其中 r < 15

 关键思想是，一旦我们确定了使用多少 15 个硬币，剩下的问题就只剩下一个小的余数 r，可以通过暴力或预计算来最佳解决。 然而，简单地占据下限（n / 15）并不总是最佳的，因为减少 15 个硬币有时可以允许较小硬币的更好组合，从而减少硬币总数。 

因此，我们不是精确地固定 k，而是尝试在 n // 15 附近设置一个小窗口，通常为 k、k-1、k-2，因为最佳解决方案只能因硬币粒度而略有偏差。 对于每个候选 k，我们计算余数并以最佳方式求解小值。 余数部分是有界的（实际小于30或45，具体取决于调整范围），因此可以通过小的DP来预先计算。 

因此，问题简化为每个测试用例尝试恒定数量的可能性，每个可能性的评估时间为 O(1)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解 DP 高达 n | 每次测试 O(n) | O(n) | 太慢了 |
 | 贪婪无修正 | O(1) | O(1) | O(1) | O(1) | 错误 |
 | 残留+局部DP| 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们使用具有五种面额的标准无界硬币 DP 预先计算一个小型 DP 表，用于存储达到固定限制（例如 30 或 45）的所有值。 这给出了任何小余数的确切的最小硬币数量。 

对于每个测试用例：

 1. 计算 k = n // 15。这是最大硬币的基线计数。

之所以选择它，是因为 15 是最大的面额，可以有效地控制大额金额。 
2. 对于 k 的候选值，考虑 k、k-1 和 k-2，跳过负值。 

原因是替换一枚 15 枚硬币会使余数增加 15，有时这可以更好地分解成更小的硬币。 
3. 对于每个候选 k，计算 r = n - 15 * k。 

这将问题简化为解决一个小的固定值实例。 
4. 如果r在预先计算的DP范围内，则将dp[r]作为成本。 

这给出了使用硬币 1、3、6、10、15 形成余数的最佳方法。 
5. 跟踪所有候选者中 k + dp[r] 的最小值。 

这结合了大量硬币的使用和最佳的余数分解。 
6. 输出最小发现值。 

### 为什么它有效

 任何最佳解决方案都可以被视为使用多少 15 个硬币以及由较小硬币组成的剩余部分的选择。 如果我们使用太多 15 个硬币，我们就会留下一小部分剩余部分，而修复这些剩余部分的成本很高。 如果我们使用太少，我们就会在大覆盖范围内浪费效率。 最佳解决方案必须接近 n // 15 的贪婪选择，因为将 k 更改超过一个小常数将改变至少 15 个单位的价值，并且这种转变无法通过超出有限范围的小硬币系统的改进来补偿。 

因此，将 k 限制为贪婪选择周围的常数邻域可以保留最优性，同时将问题简化为预先计算的有限状态空间上的常数时间查找。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

coins = [1, 3, 6, 10, 15]

MAX_R = 45
INF = 10**9

dp = [INF] * (MAX_R + 1)
dp[0] = 0

for i in range(1, MAX_R + 1):
    for c in coins:
        if i >= c:
            dp[i] = min(dp[i], dp[i - c] + 1)

def solve():
    n = int(input())
    k = n // 15
    ans = INF

    for dk in [0, -1, -2]:
        kk = k + dk
        if kk < 0:
            continue
        r = n - 15 * kk
        if 0 <= r <= MAX_R:
            ans = min(ans, kk + dp[r])

    print(ans)

t = int(input())
for _ in range(t):
    solve()
```DP表`dp`对所有小残差计算一次。 这很重要，因为它避免了跨测试用例的重新计算。 

里面`solve`，我们将解决方案锚定在 15 个硬币的贪婪数量上。 我们明确测试附近的值，因为硬币系统不是严格规范的，局部调整可以提高硬币总数。 

选择 MAX_R = 45 可确保即使将 k 减少最多 2 后，余数仍保持在 DP 有效的范围内。 这个常数界限保证了每个测试用例的 O(1) 时间复杂度。 

## 工作示例

 ### 示例 1

 输入：

 n = 16

 我们计算 k = 1。 

| k | 余数 r = n - 15k | dp[r] | dp[r] | 总计 k + dp[r] |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 2 |
 | 0 | 16 | 16 dp[16] = 2 | 2 |

 最小值为 2，可通过 15 + 1 或 10 + 6 实现。 

这表明“一个大硬币+小残留物”和“两个中等硬币”都可以是同样最优的，并且算法正确地捕获了两者。 

### 示例 2

 输入：

 n = 20

 k = 1

 | k | 余数 r | dp[r] | dp[r] | 总计 |
 | --- | --- | --- | --- |
 | 1 | 5 | 3 | 4 |
 | 0 | 20 | dp[20] = 2 | 2 |

 最佳解决方案是根本不使用 15 枚硬币。 相反，20 = 10 + 10 仅使用两个硬币。 

这说明了为什么我们必须考虑 k-1 或 k-2 调整。 纯粹贪婪地使用 15 并不是最理想的。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    coins = [1, 3, 6, 10, 15]
    MAX_R = 45
    INF = 10**9

    dp = [INF] * (MAX_R + 1)
    dp[0] = 0

    for i in range(1, MAX_R + 1):
        for c in coins:
            if i >= c:
                dp[i] = min(dp[i], dp[i - c] + 1)

    def solve_case(n):
        k = n // 15
        ans = INF
        for dk in [0, -1, -2]:
            kk = k + dk
            if kk < 0:
                continue
            r = n - 15 * kk
            if 0 <= r <= MAX_R:
                ans = min(ans, kk + dp[r])
        return ans

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str(solve_case(n)))
    return "\n".join(out)

 ## 边缘情况

 当 n = 2 时，不能使用大于 1 的硬币。 该算法计算 k = 0、r = 2 并使用 dp[2] = 2，正确返回两个 1 硬币。 

对于 n = 15，k = 1 给出 r = 0，因此答案为 1。任何减少 k 的尝试都会增加较小硬币的数量并产生更糟糕的结果。 

对于 n = 20，算法显式测试 k = 1 和 k = 0。第二个选择产生 dp[20] = 2，这是最优的。 这说明了为什么围绕 k 的邻域搜索对于正确性是必要的。
