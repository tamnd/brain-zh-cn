 ## 解决方案
 ## 问题理解

 我们有一个非常大的网格`n`行和`m`列，其中`n`和`m`每个最多可达 10^8。 在这个网格中，恰好有两个单元格在不同的坐标处包含地雷。 我们不知道地雷在哪里，但我们可以向交互器询问有关任何细胞的信息`(x, y)`通过查询它。 交互器以从该单元到两个地雷中的任何一个的最小曼哈顿距离做出响应。 我们的目标是使用最多四个查询找到至少一个地雷的准确坐标。 

由于网格可能非常大，因此不可能采用简单的方法来检查每个单元格。 曼哈顿距离是指距细胞的距离`(x, y)`到矿井`(xi, yi)`是`|x - xi| + |y - yi|`，查询返回到任一地雷的最小距离。 因此，每个查询有效地为我们提供了一个菱形的单元格区域，其中可能包含最近的地雷。 通过仔细选择查询，我们可以交叉这些钻石区域来唯一地识别矿场。 

当两个地雷彼此非常接近或沿行或列对齐时，就会出现微妙的边缘情况。 如果查询选择不当，则最小距离可能对应于任一地雷，并且如果没有适当的几何推理，人们可能会错误地得出错误的单元格包含地雷的结论。 例如，地雷位于`(1,1)`和`(1,3)`, 查询`(1,2)`回报`1`，除非我们仔细解释响应，否则这是不明确的。 

## 方法

 暴力方法是将所有单元格视为地雷的候选单元格，并尝试根据距离将它们排除在外。 对于每个查询，我们将计算从每个单元格到该查询点的距离并与候选集相交。 虽然在概念上是正确的，但这是不可行的，因为`n * m`可以达到10^16，远远超出任何计算能力。 

最佳解决方案的关键见解是曼哈顿距离允许我们以几何方式处理查询。 在网格的角落或中心进行查询会为我们提供一个候选单元格的菱形，其中最近的矿井可能位于其中。 通过在角点或中点选择最多四个策略查询，我们可以确定总和`x + y`或差异`x - y`对于其中一个矿井。 根据这些线性组合，可以唯一地重建一个地雷的坐标，而无需搜索整个网格。 固定数量的查询（四个）就足够了，因为每个查询将候选区域缩小为较小的菱形，并且这些菱形的交集隔离了单个矿井。 

这将问题从大规模搜索转变为使用曼哈顿距离属性的建设性几何演绎。 暴力破解原则上是可行的，但由于大小而失败。 最佳方法利用对称性和曼哈顿度量在最多四个查询中确定性地定位一个地雷。

 ## 算法演练

 1.查询左上角`(1, 1)`并读取距离`d1`。 这告诉我们，一个矿井位于半径为菱形的某处`d1`大约`(1, 1)`。 
2. 查询右上角`(1, m)`并读取距离`d2`。 周围的钻石`(1, m)`与第一条菱形沿一条线相交`x + y = constant`或者`x - y = constant`。 这减少了最近矿井的候选坐标。 
3.查询左下角`(n, 1)`并读取距离`d3`。 现在我们有三个相交的菱形。 该交集唯一地标识一个地雷的单个单元格或一小组候选单元格。 
4. 如有必要，经常查询第四个战略单元`(n, m)`或先前菱形的交集，以解决歧义。 此时，恰好有一个单元满足所有约束。 输出这个单元格作为地雷。 

为什么有效：每个查询都会生成一个包含最近矿井的可能位置的菱形。 通过为查询选择极端位置（角点），菱形的交点会产生以下线性方程`x`和`y`。 曼哈顿距离确保这些钻石具有可预测的形状。 通过四个精心选择的查询，交集减少为单个候选单元格，从而保证了地雷的位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def query(x, y):
    print(f"? {x} {y}")
    sys.stdout.flush()
    return int(input())

def solve_case(n, m):
    d1 = query(1, 1)
    d2 = query(1, m)
    d3 = query(n, 1)
    
    # Calculate candidate coordinates using properties of Manhattan distances
    x = (d1 + d3 + 2) // 2
    y = (d1 + d2 + 2) // 2
    
    print(f"! {x} {y}")
    sys.stdout.flush()

def main():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        solve_case(n, m)

if __name__ == "__main__":
    main()
```该解决方案首先查询三个角，这在几乎所有配置中都足以隔离一个地雷。 公式`(d1 + d3 + 2)//2`和`(d1 + d2 + 2)//2`是通过菱形求和和相交得出的：它们解决了曼哈顿距离产生的线性系统。 一个微妙之处是`+2`和整数除法以调整基于 1 的索引并保证舍入到正确的单元格。

 ## 边缘情况

 如果两个地雷位于同一行或同一列，则查询对角仍会沿该行或列生成相交的菱形。 解中的算术会自动解决这个问题，因为这些公式求解由距离定义的线性系统。 对于相邻的矿井，钻石较小，但交叉逻辑仍然在四个查询中隔离至少一个矿井。 

例如，地雷位于`(1,1)`和`(1,2)`在一个`2x2`网格、查询`(1,1)`,`(1,2)`,`(2,1)`给出回应`0,0,1`。 交集产生`(1,1)`正确地作为第一个地雷。
