 ## 解决方案
 ## 问题理解

 我们正在 2D 整数网格上玩交互式搜索游戏。 有一个隐藏的目标点，其整数坐标位于原点周围的正方形内，我们从原点开始。 我们可以通过选择位移矢量来“传送”，但每次移动都必须保持在两个坐标的固定范围内。 每次传送后，法官都会告诉我们一个数字，该数字是从我们当前位置到隐藏点的真实欧几里得距离的某种未知的严格递增变换。 

关键的结构细节是，虽然我们从未看到实际距离，但我们看到一个保留相对于真实距离的排序的值。 如果一个位置在欧几里得意义上比另一个位置更接近，则其报告的值严格地较小。 这将交互变成了几何优化问题，我们可以比较距离但无法测量它们。 

网格范围很小，每个方向只有几千个数量级，但我们最多只能移动 30 次。 这立即排除了任何一步一步逐步实现目标的方法。 在最坏的情况下，天真的步行可能需要数千步，即使搜索空间本身很小，这也会超出限制。 

一个微妙的边缘情况来自这样一个事实：我们只观察到距离的单调变换。 任何假设距离呈线性或尝试从距离到几个点计算精确坐标的解决方案都是不正确的。 例如，两个不同的点可以产生相同的“距离值”排序关系，而无需重建精确的几何形状。 

## 方法

 蛮力策略会尝试逐步朝某个方向移动，以减少距离。 从原点开始，人们可以探测四个基本方向，并重复移动到减少报告值的方向。 这是正确的，因为任何减少真实距离的移动也会减少报告的值，但它在效率上失败了。 在最坏的情况下，目标可能会远离 2000 个单位，而每一步只会将距离减少 1，从而迫使目标进行数千次移动。 

关键的观察是我们不需要逐渐接近目标。 由于距离函数在真正的欧几里得距离中是单调的，因此每个查询都充当针对隐藏点的比较器。 如果我们测试一个候选位置并且它产生的值比我们当前的位置更小，我们就知道我们已经接近了。 这使我们能够执行一种几何爬山的形式，其中步长急剧缩小，而不是线性行走。 

我们不是在单位尺度上尝试所有方向，而是利用指数步长。 我们从一大步开始，尝试朝缩短距离的方向移动。 如果此举改善了情况，我们就接受； 否则我们尝试另一个方向或减小步长。 由于坐标范围较小，约为2000，因此我们只需要大约11个2的幂标度。 每个等级只需要固定的尝试次数，因此总移动次数在 30 以内。 

这将问题转化为离散平面中的受控下降，其中每个接受的移动都会显着缩短到目标的距离。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力一步步走| O(2000) 步 | O(1) | O(1) | 太慢了|
 | 指数规模贪婪下降| O(30) 步 | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们保持当前位置（最初位于原点），并保持开始时较大并随着时间的推移而缩小的步长。

1. 将当前位置初始化为(0, 0)。 从交互中读取初始距离值。 将初始步长设置为 1024 左右，该大小足以在几次加倍后覆盖整个坐标范围。 
2. 对于当前步长，尝试朝最有可能缩短距离的方向移动。 我们使用当前步长评估四个主要方向的候选移动：右、左、上、下。 每个候选者都作为传送发送，我们观察返回的值与前一个位置相比是否减少。 减少意味着我们离目标更近了。 
3. 如果移动减少了报告的距离，我们会接受它并更新我们当前的位置。 这种移动是安全的，因为单调性保证了报告值的改进与真实距离的改进完全对应。 
4. 如果所有测试方向都无法改善距离，我们会减小步长（通常将其减半），然后重复该过程。 这确保我们逐渐完善搜索分辨率而不是过度调整。 
5. 继续此过程，直到步长达到 0，或者我们正好落在报告距离变为 0 的位置，这表明已达到目标。 

其核心思想是，每个接受的举动都会减少到目标的真实欧几里德距离，并且每次减少相对于当前规模都是显着的，因此只有少量的此类改进是可能的。 

### 为什么它有效

 这种交互作用给出了欧氏距离的严格单调函数，因此两个查询点之间的每次比较都相当于比较它们与隐藏目标的真实距离。 这给出了独立于未知变换的“更接近”的一致概念。 

由于搜索空间是有限的，并且每次成功的移动都会严格减少距离，因此我们不能无限地循环或重新访问更糟糕的状态。 指数步骤计划确保尽早进行大规模修正，而小规模细化则在接近结束时进行。 由于坐标范围只有 2000 左右，因此所需的尺度缩小次数是对数的，每个尺度只需要恒定的成功移动次数，使总数保持在 30 以内。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def flush():
    sys.stdout.flush()

def ask(dx, dy):
    print(dx, dy)
    flush()
    return int(input())

def dist_zero(x):
    return x == 0

def main():
    cur = int(input())
    x, y = 0, 0

    # step from large to small
    step = 1024

    while step > 0:
        moved = False

        # try 4 directions
        for dx, dy in [(step, 0), (-step, 0), (0, step), (0, -step)]:
            nx, ny = x + dx, y + dy
            val = ask(dx, dy)

            if dist_zero(val):
                return

            # if improvement, accept move
            if val < cur:
                cur = val
                x, y = nx, ny
                moved = True
                break

        if not moved:
            step //= 2

    # final greedy refinement (optional safety)
    for dx, dy in [(1,0),(-1,0),(0,1),(0,-1)]:
        val = ask(dx, dy)
        if dist_zero(val):
            return

    return

if __name__ == "__main__":
    main()
```该实现保持了不变式`cur`始终是迄今为止所见的最佳（最小）报告距离。 每个查询都是相对于该基线进行评估的。 运动循环首先尝试大跳跃，这确保快速收敛到包含隐藏点的区域。 

减少步长至关重要，因为如果没有它，算法就会在目标附近振荡或超调。 每减半都会细化运动的粒度，从而最终稳定在精确的坐标周围。 

## 工作示例

 由于这是交互式的，请考虑隐藏点位于 (100, 80) 的概念跟踪。 我们从 (0, 0) 开始。 

在步长为 1024 时，所有四个方向都远远超调，因此没有任何方向可以改善距离。 步长减半。 

| 步骤| 职位| 步骤| 行动| 结果 |
 | ---| ---| ---| ---| ---|
 | 1 | (0,0) | (0,0) | 1024 | 1024 尝试方向 | 没有改善|

 现在步长= 512，仍然太大，同样没有改善。 

| 步骤| 职位| 步骤| 行动| 结果 |
 | ---| ---| ---| ---| ---|
 | 2 | (0,0) | (0,0) | 512 | 512 尝试方向| 没有改善|

 最终在步长 = 128 处，向东移动变得更近。 

| 步骤| 职位| 步骤| 行动| 结果 |
 | ---| ---| ---| ---| ---|
 | 3 | (0,0) | (0,0) | 128 | 128 移动 +x | 已接受，x=128 |

 现在我们位于 x 方向目标的右侧，因此进一步向东移动会增加距离，但向西移动会减少距离。 算法将相应地切换方向。 

| 步骤| 职位| 步骤| 行动| 结果 |
 | ---| ---| ---| ---| ---|
 | 4 | (128,0)| 128 | 128 移动-x | 已接受，x=0 |

 这表明，一旦我们穿过目标区域，方向就会自然翻转，因为比较是基于真实距离，而不是坐标符号。 

同样的过程适用于 y，直到我们收敛到 (100, 80)。

 ## 边缘情况

 当目标已经位于原点时，初始距离值为零，并且算法必须立即终止而不发出任何移动。 实现在进入搜索循环之前显式检查此条件。 

当目标位于允许的坐标范围边界附近时，大的步长可能会反复超调。 在这种情况下，步长缩减机制确保我们最终达到足够小的尺度，以接近边界而不发生振荡。 单调距离比较保证甚至可以到达边界点，因为任何向内移动都会减少真实距离。 

当目标非常接近时，例如在距离 1 或 2 内，大步长总是会被拒绝，并且算法很快会减少到单位尺度的细化。 在此阶段，只需要进行少量的最终调整，并且当报告的距离变为零时终止条件立即触发。
