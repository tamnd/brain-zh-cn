 ## 解决方案
 ## 问题理解

 我们得到一个位置数组，其中每个位置 i 都带有一个数字 a[i]。 该数字旨在表示在 1 到 n 的某个隐藏排列 p 中恰好在位置 i 处结束的最长严格递增子序列的长度。 

任务是重建任何可以精确产生这些 LIS 结尾长度的排列 p，或者确定不存在这样的排列。 

关键的困难在于 a[i] 没有描述像数组的整体 LIS 这样的全局属性。 它是一个与所有早期位置相互作用的每个位置约束：如果位置 i 可以结束一个长的递增子序列，那么必须有一个一致的早期值模式来支持它，同时我们必须避免意外创建比允许的更长的子序列。 

约束足够大，任何 n 的二次方都是不可能的。 构建或验证必须以基本上线性或 n log n 的时间运行，因为 n 可以达到一百万。 这排除了任何尝试模拟每个候选排列的 LIS 计算或在临时分配后重复重新计算子序列的尝试。 

当给定数组违反单调可行性条件时，会出现微妙的边缘情况。 例如，如果序列需要增加 LIS 长度，但没有提供足够的结构来支持它们，则任何排列都无法满足它。 另一个有问题的情况是，当局部排序约束在 a[i] 的相等值上强制产生矛盾时，因为相等的 LIS 长度对容易被忽视的值施加了严格的排序约束。 

## 方法

 暴力方法会尝试生成排列并计算每个位置的 LIS 结尾长度，并将它们与给定数组进行比较。 即使我们限制自己的排列，也有 n！ 可能性，并且每个 LIS 计算都是 O(n log n)，这使得这完全不可行。 

思考该问题的一种更结构化的方法是反转 LIS 结尾长度的定义。 我们不询问排列产生的 LIS 长度，而是将每个位置视为需要有向结构中的某个“层”：如果 a[i] = k，则位置 i 必须位于某个递增链结构中的深度 k 处。 任何有效的排列必须允许长度为 k 的链以 i 结尾，并且必须禁止任何长度超过 k 的链以 i 结尾。 

关键的观察结果是，LIS 结束值引起的约束在很强的意义上是单调的。 如果位置 j 位于 i 之前且 a[j] ≥ a[i]，则 j 无法促成以 i 结尾的递增子序列，因为这会立即创建一个比允许的长度更长的子序列。 这迫使值之间存在结构排序，这可能会转化为构造问题：我们必须分配数字，以便尊重这些主导关系。 

一旦正确解释了这一点，问题就变成了构建与数组 a 引起的偏序一致的排列，同时确保每个位置准确地达到其所需的 LIS 深度。 贪婪的分层构造之所以有效，是因为 LIS 结尾值所隐含的结构本质上是分层的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力排列 + LIS 检查 | O(n!·n log n) | O(n!·n log n) | O(n) | 太慢了|
 | 分层贪婪构造| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们通过按照尊重 LIS 层的仔细控制的顺序分配从 1 到 n 的值来构建排列。 

1. 按值 a[i] 对所有索引进行分组，为每个可能的 LIS 深度形成桶。

这反映了具有相同所需 LIS 结束长度的位置必须被视为单个结构层的想法。 
2. 按照 a[i] 的递增顺序处理层，从 1 开始直到出现的最大值。 

较低层必须在排列中接收较小的值，否则较高层元素可能会错误地通过它们扩展子序列。 
3. 在每层 k 内，按照位置索引 i 的降序对索引进行排序。 

这种逆转是必要的。 如果 j < i 并且两者都属于同一层，则将较小的值分配给较早的位置将意外地允许增加的子序列在同一层内向前传播，这将违反以 i 结尾的 LIS 恰好是 k 的要求。 
4. 使用从 1 增加到 n 的全局计数器按顺序为这些位置赋值，首先填充第 1 层中的所有索引，然后填充第 2 层中的所有索引，依此类推。 

这确保了层之间的严格分离，因此任何增加的子序列都必须遵守层结构。 
5. 输出排列结果。 

### 为什么它有效

 该构造同时强制执行两个单调属性。 首先，值随着 LIS 层的增加而增加，因此任何增加的子序列只能从较低层移动到较高层，而不能向后移动。 其次，在固定层内，按索引递减分配可以防止同一层内递增子序列的前向传播。 

因此，任何以位置 i 结尾的递增子序列必须从 a[i] 下面的每一层中选取至多一个元素，并且该构造保证可以准确地链接 a[i] 层以到达 i，而添加任何额外元素将强制违反层顺序或索引顺序。 这会将 LIS 结束长度固定为所需的值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    maxv = max(a)
    buckets = [[] for _ in range(maxv + 1)]

    for i, v in enumerate(a):
        buckets[v].append(i)

    p = [0] * n
    cur = 1

    for val in range(1, maxv + 1):
        # assign larger values later layers
        # within layer: process indices in decreasing order
        for i in sorted(buckets[val], reverse=True):
            p[i] = cur
            cur += 1

    # quick validation: ensure it's a permutation
    if cur != n + 1:
        print(-1)
        return

    print(*p)

if __name__ == "__main__":
    solve()
```实现直接遵循逐层分配。 唯一微妙的实现选择是在分配值之前按索引降序对每个存储桶进行排序。 该顺序强制执行层内约束，以防止相等层位置形成意外的递增子序列。 

全局计数器确保所有值都是不同的，并且恰好涵盖 1 到 n，因此只要构造成功，输出就是有效的排列。 

## 工作示例

 考虑输入 a = [1, 2, 2, 3, 3]。 

我们首先按层对索引进行分组。 

| 步骤| 层| 指数（按顺序排序）| 指定值| 当前计数器 |
 | ---| ---| ---| ---| ---|
 | 1 | 1 | [0]| p[0] = 1 | p[0] = 1 2 |
 | 2 | 2 | [2, 1] | p[2] = 2，p[1] = 3 | 4 |
 | 3 | 3 | [4, 3] | p[4] = 4，p[3] = 5 | 6 |

 这会产生一个排列，其中较高的 LIS 层始终接收较大的值，而在每层内，后面的位置会获得较小的分配值。 

该轨迹显示了算法如何按 LIS 深度分离结构，同时仍保持完整排列。 

现在考虑一个较小的情况 a = [1, 1, 2, 1, 4, 4, 4]。 

我们再次逐层处理。 

| 步骤| 层 | 指数（描述）| 作业 |
 | ---| ---| ---| ---|
 | 1 | 1 | [3, 1, 0] | 最小值进入层 | 中后面的索引
 | 2 | 2 | [2] | 下一个值 |
 | 3 | 4 | [6,5,4]| 此处指定的最大值 |

 这演示了较高层如何在排列顺序中自然地支配较低层，从而保留所需的 LIS 结构。

 ## 边缘情况

 对于所有 a[i] 相等的输入，例如 a = [2, 2, 2]，该算法将所有索引放入同一层，并按相反的索引顺序分配值。 这保证了较早的索引接收更大的值，从而防止同一层内意外增加的子序列。 每个位置的 LIS 结束长度都保持为 2，因为没有有效的链可以延伸到单层转换之外。 

对于像 a = [1, 2, 1] 这样的输入，第一个和第三个位置共享第 1 层，而第二个位置位于第 2 层。该结构分配值，以便第 2 层位置接收最大值，强制以该位置结尾的任何递增子序列都来自第 1 层元素。 第 1 层内的降序确保不会发生跨层膨胀，从而保留精确的 LIS 长度。
