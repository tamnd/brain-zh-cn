 ## 解决方案
 ## 问题理解

 我们正在模拟在九个单元的线性轨道上玩的小型棋盘游戏。 最初，三个不同的棋子被放置在固定位置：紫色棋子从单元 2 开始，绿色棋子从单元 3 开始，黄色棋子从单元 4 开始。 

游戏通过每个测试用例 12 个命令的序列进行。 每个命令指定一种颜色和移动距离。 执行命令会沿线向左或向右移动相应的彩色块。 

关键在于碎片可以堆叠。 如果移动的棋子到达已被其他棋子占据的单元格，则将其放置在现有棋子堆的顶部。 更重要的是，如果一个棋子在它的堆栈中不是单独的，那么移动它会拖动它上面的所有棋子。 这使得系统的行为就像一组动态堆栈，可以随着时间的推移合并和分裂，具体取决于移动的着陆位置以及堆栈中的哪个棋子被选择。 

处理完所有 12 个命令后，我们需要确定所有三个部分是否同时到达单元 9，无论它们在堆栈中的内部顺序如何。 

这些约束在结构上非常严格，但国家规模却很小。 每个测试用例都有一个固定长度的 12 个操作序列，以及最多 10^4 个测试用例。 这立即排除了任何对大型结构进行大量每次操作模拟的解决方案。 然而，总数量只有三个，这强烈表明只要每个操作在恒定或接近恒定的时间内处理，带有仔细状态跟踪的直接模拟就足够了。 

堆栈移动规则产生了一个微妙的边缘情况。 简单的实现可能只跟踪每种颜色的位置并忽略堆栈结构。 当堆栈中间的棋子移动时，这会失败，因为它错误地将其上方的棋子留在后面。 

例如，假设紫色位于单元格处，绿色堆叠在其上方，并且命令移动紫色。 然后紫色和绿色必须一起移动。 仅跟踪每种颜色坐标的幼稚模型会错误地单独移动紫色。 

当发生多次合并时，会出现另一种失败情况。 一旦堆栈合并，未来的操作就可以通过多种颜色传播，因此我们必须保留每个堆栈内的顺序。 

## 方法

 强力解释将明确模拟棋盘和所有堆栈。 我们维护九个列表，每个列表代表一堆碎片。 每次移动都需要在当前堆栈中找到目标块，拆分列表，并将后缀移动到另一个堆栈。 由于堆栈很小，这已经是可行的，但我们必须精确地定位和切割段。 

在最坏的情况下，每个操作可能需要扫描大小最多为 3 的堆栈来定位移动块，然后对列表进行切片。 这在实践中是恒定的时间，但如果不小心实施的话，结构仍然会有点尴尬。 

关键的观察是整个系统最多有三个对象，而堆栈交互只是这些对象在九个位置上的排列。 我们不需要高级的数据结构。 直接基于列表的模拟就足够了，只要我们维护每个单元的堆栈内容以及堆栈中每个部分的位置。 

蛮力方法虽然有效，但在仅使用位置跟踪来实施时变得脆弱。 正确的见解是状态足够小，我们可以显式地维护每个位置的完整堆栈，并在每次移动后一致地更新它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（不正确的仅位置模拟）| 每次移动 O(1) 但不正确 | O(1) | O(1) | 错误 |
 | 最优堆栈模拟 | 每次移动 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

我们将棋盘保持为九个堆栈，每个堆栈都是从下到上的颜色列表。 我们还为每种颜色维护它当前所属的堆栈。 

1. 初始化九个空栈，并将紫色、绿色和黄色分别放置在位置 2、3 和 4 处。 每个都是一个单元素堆栈。 
2. 对于每个操作，识别包含给定颜色的堆栈。 我们不仅找到堆栈，还找到该堆栈中颜色的索引。 该索引至关重要，因为从该位置向上的所有内容都会一起移动。 
3. 将堆栈分成两部分：所选棋子下方的部分保留在原始单元格中，所选棋子上方的部分作为块移除。 
4. 通过将移动值添加到当前索引来计算目标单元格。 
5. 将移动的块追加到目标堆栈上，保留顺序。 
6. 更新移动块中每种颜色的记录位置，因为它们的单元格已更改。 
7. 处理完所有操作后，检查所有三种颜色是否都位于堆栈的第 9 号单元格中。 

正确性取决于以下事实：每个操作仅移动堆栈的连续后缀，并且每次移动后堆栈始终保持正确的顺序。 

### 为什么它有效

 在任何时候，每个单元都存储一个堆栈，该堆栈反映了到达那里的碎片的确切垂直顺序。 由于仅移动后缀，因此任何移动组内的相对顺序都不会改变。 每一个操作都保留了这样的不变性：每一块都属于一个堆栈，并且堆栈顺序与历史堆栈顺序相匹配。 由于模拟准确地反映了规则，因此最终的配置忠实于所描述的过程。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        stacks = [[] for _ in range(10)]
        pos = {}

        # initial positions
        stacks[2] = [1]
        stacks[3] = [2]
        stacks[4] = [3]
        pos[1] = 2
        pos[2] = 3
        pos[3] = 4

        for _ in range(12):
            a, b = map(int, input().split())
            c = a
            cur = pos[c]
            stack = stacks[cur]

            idx = stack.index(c)
            moving = stack[idx:]
            stacks[cur] = stack[:idx]

            nxt = cur + b
            stacks[nxt].extend(moving)

            for x in moving:
                pos[x] = nxt

        if pos[1] == 9 and pos[2] == 9 and pos[3] == 9:
            print("Y")
        else:
            print("N")

if __name__ == "__main__":
    solve()
```该解决方案直接对堆栈模型进行编码。 每个堆栈都是一个 Python 列表，切片将移动的部分与保留的部分完全分开。 字典`pos`确保我们可以立即找到任何颜色的当前单元格。 

唯一微妙的实现细节是使用`index`找到该块在其堆栈中的位置。 由于堆栈大小最多为 3，因此这实际上是常数时间。

 ## 边缘情况

 一种边缘情况是当移动选择堆栈的底部元素时。 在这种情况下，整个堆栈都会被移动，原始单元格会变空。 该实现自然地处理了这个问题，因为从索引零开始切片会返回完整列表并留下一个空前缀。 

另一种边缘情况是重复合并和分裂。 堆栈可能会形成，在中间分裂，然后在另一个位置重新组合。 因为我们总是通过显式列表重建堆栈，所以不会丢失历史依赖性，并且每个操作都会重新计算确切的结构。 

最后一个微妙的情况是多件货物以不同的顺序降落在同一目的地。 该算法保留了到达顺序，因为每个移动的块都附加在目标堆栈的末尾，这符合问题的规则，即新到达的块位于现有块的顶部。
