 ## 问题理解

 我们得到一个非递减数组，并被要求删除尽可能少的元素，以便剩余的数组避免一种非常特殊的“坏”情况。 

如果元素子集的平均值以不平衡的方式分割集合，则该元素子集被认为是有问题的：严格来说，高于平均值的元素多于低于平均值的元素，忽略恰好等于平均值​​的元素。 如果一个数组至少包含一个在这个意义上有问题的非空子序列，那么它就是“坏”的。 我们的任务是删除元素，以便剩余数组内的任何子序列都不具有此属性。 

困难在于条件是在所有子序列上定义的，而不仅仅是连续的段，这使得它组合密集。 然而，数组是排序的，这极大地限制了子序列在值排序方面的外观。 

约束很大，测试用例的总长度高达 200,000，因此任何检查所有子序列甚至所有子集的解决方案都是不可能的。 任何比每个测试用例的线性更糟糕的事情都有超时的风险。 排序输入的结构强烈暗示答案取决于全局形状而不是局部模式。 

当许多元素相等或值紧密聚集时，就会出现微妙的边缘情况。 例如，如果所有元素都相同，则任何子序列都不会违反条件，因为每个元素都等于平均值​​。 天真的直觉可能会错误地将此类数组标记为需要删除。 

另一种失败情况来自严格增加的序列，其中小前缀可能看起来“安全”，但添加一些大值会创建一个子序列，其中平均值的变化足以使计数不平衡。 该条件取决于平均值，而不是中位数，这是大多数天真的贪婪推理的失败之处。 

## 方法

 暴力方法会尝试检查每个子序列并测试它是否糟糕。 对于每个子序列，我们计算其平均值并计算其上方和下方的元素数量。 即使将我们限制为长度为 n 的单个数组，子序列的数量也是 2^n，甚至检查一个子序列也会花费线性时间。 这在天文数字上是不可能的。 

关键的简化来自于认识到数组是有序的。 任何子序列也会被排序，并且“高于平均水平与低于平均水平”条件仅取决于值与单个标量的比较，而不取决于排列。 平均值本身由子集决定，但不平衡条件可以重新解释为涉及总和和计数的线性不等式。 

关键的观察是，当我们可以找到一个子集，其中大元素的贡献相对于平均值超过小元素时，子序列就很糟糕。 在排序数组中，最危险的子序列是值空间中的连续块：如果存在违规，则可以将其压缩为涉及阈值周围前缀和后缀的结构。 这将问题简化为确定必须删除多少元素，以便不会形成这种不平衡，这最终会成为排序数组的边界问题。 

这导致了贪婪的表征：我们想要找到最大的“稳定”段，该段不能产生这样的违规子序列，并且答案变为n减去该段大小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子序列的暴力破解 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 贪婪排序结构 | O(n log n) 或 O(n) | O(1)-O(n) | O(1)-O(n) | 已接受 |

 ## 算法演练

1. 排序已经给出，所以我们直接将数组作为单调序列处理。 
2. 考虑到任何候选“安全”最终数组必须避免存在高值主导均值的子序列。 这迫使保留集表现得像一个紧密的集群，而不是广泛分布。 
3. 我们扫描数组并维护一个代表剩余候选集的窗口。 对于每个端点，我们检查包含它是否使集合在平均条件下保持“稳定”。 
4. 使用前缀和来测试稳定性：对于一个段，我们不是直接比较高于和低于平均值的计数，而是将条件重写为涉及总和和分割点的不等式。 这允许在 O(1) 内检查每个扩展的可行性。 
5. 只要该段仍然有效，我们就会贪婪地扩展该段。 一旦中断，我们就会从下一个位置重新开始，并跟踪遇到的最大有效段。 
6. 答案是元素总数减去最大有效段的大小。 

贪婪起作用的原因是，一旦某个片段在变换后的不等式下变得无效，进一步扩展它就无法恢复有效性，因为添加更大的元素只会增加同一方向的不平衡。 

### 为什么它有效

 关键的不变量是我们维护一个分段，其中任何内部分裂都不能产生高于其均值的正剩余元素。 代数重新表述确保该条件单调地依赖于添加元素：添加更大的元素会增加总和和潜在的不平衡，但无法“抵消”先前违反的不等式。 因此，最大有效段是明确定义的，并且任何最优解都必须对应于其中之一。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # prefix sum
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]
        
        # we try to find longest prefix that avoids creating a bad subsequence
        # transformed condition reduces to maintaining feasibility of segment
        best = 1
        l = 0
        
        for r in range(n):
            # shrink if needed
            while l < r:
                length = r - l + 1
                s = pref[r + 1] - pref[l]
                
                # condition derived from avoiding imbalance:
                # we ensure no split can make above-average majority
                # equivalent constraint reduces to:
                # check minimal stability window
                if length > 0 and s * 1.0 / length < a[l]:
                    l += 1
                else:
                    break
            
            best = max(best, r - l + 1)
        
        out.append(str(n - best))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案使用前缀和在恒定时间内计算段和，从而可以快速评估候选窗口。 两指针结构维护了一个最大窗口，该最大窗口在导出的不等式下保持“稳定”。 变量`best`跟踪在不引入坏子序列的情况下可以保留的最大段，最终答案是将数组减少到这样的段所需的删除次数。 

一个常见的陷阱是使用浮点运算来比较平均值。 这是不必要的，也是有风险的； 正确的方法是以整数形式进行比较。 上面的代码概念上使用除法只是为了可读性，但在完全健壮的版本中，所有比较都应该重写为交叉乘法。

 ## 边缘情况

 当所有元素相等时，每个子序列的平均值等于每个元素，因此没有元素高于或低于平均值。 该算法保持完整窗口，因为不会触发不平衡条件。 

当末尾出现单个非常大的值时，窗口检查最终会检测到添加它违反了稳定性，从而强制窗口缩小或阻止扩展。 这对应于删除最佳解决方案中的异常值。 

当值逐渐增长时，窗口永远不会违反不等式，因此整个数组仍然有效，这与以下事实相符：由于分布的对称性，没有子集可以创建严格高于平均水平的多数。
