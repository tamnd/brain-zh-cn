 ## 解决方案
 ## 问题理解

 我们有一个人的集合，其中每个人都拥有等于其指数的固定财富，因此人 1 有 1 美元，人 2 有 2 美元，依此类推，直到 n。 我们想从这些人中选择一部分来邀请参加聚会。 

每个人都有两个限制。 如果i人被邀请，只有在所有被邀请的客人中，最多有a_i个人比他们富有，最多有a_i个人比他们贫穷时，他们才同意参加。 由于财富与指数严格相关，因此在所选子集中，“更富有”意味着更高的指数，“更穷”意味着更低的指数。 

任务是最大化受邀者的数量，使得每个受邀者都满足最终选择的集合的两个约束。 

关键的困难在于每个人的条件取决于所选子集的全局结构，而不仅仅是该人个人。 添加或删除一个人可能会同时使多个约束失效。 

这些约束允许跨测试用例的 n 最大为 2×10^5，这排除了尝试所有子集的任何方法。 子集枚举将是指数级的，甚至对每个候选者进行二次检查也会太慢。 我们需要 O(n log n) 或 O(n) 左右的东西。 

一个微妙的边缘情况来自对称约束。 例如，一个人可能允许许多较富有的人，但很少有较贫穷的人，反之亦然。 如果我们贪婪地按照递增的索引顺序挑选人员，我们很容易违反后面元素的“较差”约束。 相反，仅通过约束任意选择可能会失败，因为可行性取决于子集的最终大小，而不是绝对计数。 

## 方法

 蛮力的想法是尝试每个人的子集，并针对每个子集检查所有选定的人在放入该子集中时是否满足其约束。 对于固定子集，我们可以为每个人 i 计算有多少个选定的索引小于和大于 i，并验证 a_i 和 b_i。 如果仔细完成，此检查每个子集的时间复杂度为 O(n)，但有 2^n 个子集，使得总数完全不可行。 

关键的观察是，如果我们已经将最终组的大小固定为 k，那么每个选定的人 i 都必须按大小 k 的线性顺序放置在某个位置，其中某些位置恰好在他们之前，有些位置在他们之后。 如果我们想象按索引对选定的人进行排序，那么对于个人 i，较穷的人的数量就是其在该排序子集中的位置，而较富有的人的数量是 k 减去该位置再减一。 

因此，如果我们决定子集大小 k，我们实际上是在问是否可以选择 k 个索引并将它们分配位置 0 到 k−1，以便每个选定的 i 可以占据某个位置 p 满足 p ≤ b_i 和 k−1−p ≤ a_i。 这成为 p 的区间约束：p 必须位于 [k−1−a_i, b_i] 中。 

因此，每个人都定义了它可以在大小为 k 的子集中占据的有效位置范围。 问题就变成了：我们能否将 k 个人分配到 k 个位置，以便每个人在其允许的区间内分配到不同的位置？ 这是经典的间隔贪婪可行性检查。 

我们可以二分查找 k，因为如果可以构建大小为 k 的有效集合，那么通过删除元素也可以实现任何更小的大小。 

对于固定的 k，我们按区间的左端点对所有人进行排序，并贪婪地将他们分配到从 0 到 k−1 的位置，始终选择最早可用的有效候选者。 我们维护一个排序候选者的指针和可用右端点的最小结构。

 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 二分查找+贪心| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

1. 我们在 [0, n] 范围内使用二分搜索来确定候选答案 k。 目标是测试我们是否可以构建一个大小为 k 的有效组。 单调性之所以成立，是因为从有效配置中删除人员可以保持有效性。 
2. 对于每个人 i，如果他们包含在大小为 k 的组中，我们计算有效位置的范围。 从对穷人的约束来看，他们的位置p必须满足p≤b_i。 对于较富有的人来说，p 必须满足 k−1−p ≤ a_i，这使得 p ≥ k−1−a_i。 因此每个人贡献一个区间 [L_i, R_i] = [k−1−a_i, b_i]。 
3. 我们丢弃任何区间无效的人，即 L_i > R_i，因为这样的人不能包含在该 k 的任何有效分配中。 
4. 我们按 L_i 对剩余的区间进行排序。 我们将模拟按升序分配从 0 到 k−1 的位置。 
5. 我们将位置 p 从 0 迭代到 k−1。 在每一步中，我们将所有 L_i ≤ p 的区间添加到可用候选池中。 这些人有可能占据 p 职位。 
6. 在所有可用候选者中，我们选择 R_i 最小的一个。 这很重要，因为它保留了未来职位的灵活性。 R_i 较小的人未来的机会较少，因此尽早分配它们可以避免阻碍可行性。 
7. 如果在任何时候都没有候选位置 p，我们就得出结论，大小 k 是不可能的。 
8. 如果从 0 到 k−1 的所有位置都被成功填充，则 k 是可行的。 

二分搜索使用此可行性检查来找到最大 k。 

### 为什么它有效

 正确性依赖于标准的贪婪匹配不变量：在每个位置 p，如果可以进行任何分配，则选择具有最小右端点的可用区间永远不会减少完成分配的机会。 任何较早使用较大右端点的替代分配只能更严格地限制未来的放置，因为未来的位置需要向右延伸足够远的间隔。 这确保了贪婪过程相当于检查位置和区间约束之间是否存在完美匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(k, arr):
    intervals = []
    for a, b in arr:
        l = k - 1 - a
        r = b
        if l <= r:
            intervals.append((l, r))
    if len(intervals) < k:
        return False

    intervals.sort()
    import heapq

    heap = []
    i = 0
    n = len(intervals)

    for p in range(k):
        while i < n and intervals[i][0] <= p:
            heapq.heappush(heap, intervals[i][1])
            i += 1

        while heap and heap[0] < p:
            heapq.heappop(heap)

        if not heap:
            return False

        heapq.heappop(heap)

    return True

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = [tuple(map(int, input().split())) for _ in range(n)]

        lo, hi = 0, n
        ans = 0

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(mid, arr):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()
```核心转换是从“更丰富和更差的约束”到假设排序子集内的位置间隔约束的转换。 二分搜索包含此可行性检查以找到最大可能的子集大小。 

里面`can(k, arr)`，我们完全按照推理中的推导出来计算每个区间。 任何不存在此 k 区间的人都会被自动排除，因为他们无法参与任何有效的安排。 

堆确保我们总是选择当前位置右边界最小的参与者，这是保留未来可行性的贪婪选择。 

二分搜索循环重复调用该检查器，有效地缩小答案范围。

 ## 边缘情况

 一个关键的边缘情况是，许多参与者的 b_i 值非常严格，迫使他们提前持仓。 例如，如果几个人最多只允许0个较穷的人，那么他们都需要位置0，这超出了一种选择是不可能的。 间隔构造将其转换为 0 处的重叠右端点，导致堆在需要第二个此类间隔的第一次分配时失败。 

另一种边缘情况发生在一个人的 a_i 较大但 b_i 很小时，这意味着他们可以容忍许多富有的人，但必须出现在排序的早期。 该算法自然会优先考虑它们，因为它们的右端点很小，因此它们会被提前选择，并且不会阻塞后面的位置。 

最后一种情况是当 k 很大但许多区间在变换后变得无效时。 支票`l <= r`立即删除此类候选者，确保二分搜索不会仅根据原始计数错误地假设可行性。
