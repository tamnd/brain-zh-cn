 ## 解决方案
 ## 问题理解

 我们得到了多组应用程序，每个应用程序都属于一个类别。 对于一个类别来说，唯一重要的是它包含多少个应用程序，因此输入可以被压缩为每个不同类别的频率。 

我们必须将所有应用程序放入“屏幕”中。 每个屏幕对于整个解决方案都有固定的大小，表示为$s$，但我们只能使用两种类型的屏幕：尺寸完全填充的屏幕$s$，以及几乎填满屏幕的尺寸$s-1$。 一个关键的限制是，一个屏幕只能包含单个类别的应用程序，但不同的屏幕可以自由地重复使用同一类别。 

对于固定选择$s$，每个类别的频率$x$必须分为大小为以下之一的组$s$或者$s-1$。 此类组的数量是该类别贡献的屏幕数量。 目标是选择$s$每个类别都有一个有效的分区，以便最大限度地减少屏幕总数。 

输入大小在测试用例中达到 200 万个总元素，因此任何尝试显式模拟分组或尝试搜索每个类别的分区的解决方案都会太慢。 该解决方案必须将每个测试用例简化为基本上线性的频率处理，理想情况下使用少量的候选值$s$。 

当贪婪地思考每个类别时，就会出现一个微妙的问题。 人们很容易假设对于一个固定的$s$，每个类别总是使用$\lceil x/s \rceil$屏幕。 这并不总是有效，因为“$s-1$”灵活性，可以强制使用不同数量的屏幕，甚至可以选择$s$无效的。 

一个简单的例子说明了其中的复杂性。 认为$s = 3$并且一个类别有$x = 1$。 单屏尺寸$s-1 = 2$已经超出了错误方向的容量限制：任何分解都会强制屏幕大小至少为 2，因此我们根本无法表示 1。 所以不是每一个$s$在全球范围内都是可行的。 

当贪婪上限在本地工作但违反了下限时，会发生另一个微妙的失败$s-1$屏幕。 这使得问题不仅仅涉及分区，还涉及验证所选的是否有效$s$所有类别的结构都是一致的。 

## 方法

 蛮力的想法是尝试所有可能的值$s$从 2 到最大频率，并且对于每个$s$，通过尝试所有可能的组合来计算每个类别的最小屏幕数量$s$和$s-1$组。 对于每个尺寸类别$x$，这需要解决一个小整数可行性问题或迭代可能的组数。 对所有类别和所有内容进行总结$s$，这很容易达到$O(n^2)$在最坏的情况下，这远远超出了限制。 

关键的结构观察是类别不会相互作用，除非通过共同选择$s$。 一次$s$固定后，每个类别就成为一个独立的一维包装问题。 唯一的全局约束是相同的$s$必须适用于每个类别。 

对于固定的$s$，如果我们表示为$k(x)$用于某一尺寸类别的屏幕数量$x$，那么那些$k(x)$屏幕必须满足总容量间隔$[k(x)(s-1), ks]$包含$x$。 尽可能少的屏幕数量自然接近$\lceil x/s \rceil$，但可行性取决于是否可以使用剩余结构进行调整$s-1$垃圾箱。 

这导致了一个关键的简化：对于一个有效的$s$，最优解总是使用$k(x) = \lceil x/s \rceil$对于每个类别。 如果此分配违反了下限$k(x)(s-1) \le x$对于任何类别，那么该值$s$完全无效。 增加并没有什么好处$k(x)$，因为这样做只会增加屏幕总数并使下限更加严格。 

因此，任务简化为评估候选值$s$, 计算$\sum \lceil x_i / s \rceil$，并检查可行性。 

剩下的问题是哪些值$s$必须经过测试。 约束的结构意味着唯一有意义的断点出现在从频率本身导出的值处，因为$\lceil x/s \rceil$仅当$s$的约数$x$。 这允许将注意力限制在每个周围的一小部分候选人上$x$，而不是所有整数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力胜过一切$s$和隔断|$O(n \cdot \max c_i)$|$O(n)$| 太慢了 |
 | 尝试候选人$s$，计算计数并验证 |$O(n \sqrt{n})$最坏情况天真，优化为$O(n)$摊销|$O(n)$| 已接受 |

 ## 算法演练

 1. 统计每个类别的频率。 将数组替换为正整数列表$x_1, x_2, \dots, x_k$。 这减少了问题的规模并消除了不相关的排序。 
2. 建立一组候选值$s$。 对于每个频率$x$， 包括$x$和$x+1$作为潜在候选人。 这些要点涵盖了如何实现所有结构性变化$\lceil x/s \rceil$行为。 
3. 对于每位候选人$s$，计算暂定的屏幕数量：$$m(s) = \sum_i \left\lceil \frac{x_i}{s} \right\rceil.$$4.对于同样的$s$，使用约束验证每个类别的可行性：$$m_i(s) \cdot (s-1) \le x_i,$$在哪里$m_i(s) = \lceil x_i / s \rceil$。 如果任何类别违反了这个不等式，则丢弃这个$s$。 
5. 保持最低限度$m(s)$在所有可行的候选人中。 

关键的推理步骤是一旦$s$是固定的，增加每个类别的屏幕数量只会降低容量效率，无助于满足全局约束。 因此，上限分配是唯一值得测试的候选者。 

### 为什么它有效

 对于固定的$s$，每个类别必须分为大小组$s$或者$s-1$。 任何有效分区$k$群体必须​​满足$k(s-1) \le x \le ks$。 尽可能最小的$k$可以满足上界的是$\lceil x/s \rceil$，以及任何更大的$k$只会增加左侧，同时使解决方案变得更糟。 

因此，可行性减少为检查自然贪婪分配是否$k = \lceil x/s \rceil$也满足下界。 如果是这样，那么它是最佳的$s$; 如果没有，任何调整都无法修复它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))

        freq = {}
        for x in arr:
            freq[x] = freq.get(x, 0) + 1

        xs = list(freq.values())

        candidates = set()
        for x in xs:
            candidates.add(x)
            candidates.add(x + 1)

        best = n

        for s in candidates:
            if s <= 1:
                continue

            ok = True
            total = 0

            for x in xs:
                k = (x + s - 1) // s
                if k * (s - 1) > x:
                    ok = False
                    break
                total += k

            if ok:
                best = min(best, total)

        print(best)

if __name__ == "__main__":
    solve()
```该解决方案首先将类别压缩为频率，因为只计算物质。 候选生成步骤使用最佳转变发生在每个频率值附近的观察结果。 

的计算$k = \lceil x/s \rceil$是固定屏幕尺寸的自然贪婪分配。 可行性检查强制要求，即使使用允许的最小屏幕，仍然可以打包类别，而不会违反由$s-1$屏幕。 

最终最小值取所有有效值$s$。 

## 工作示例

 ### 示例 1

 输入类别：$[1, 5, 1, 5, 1, 5, 1, 1, 1, 1, 5]$频率是$1 \to 6$,$5 \to 5$，所以我们有$xs = [6, 5]$。 

我们测试一个候选人$s = 3$。 

| 类别 x | k = ceil(x/s) | k(s-1) ≤ x? | 贡献 |
 | ---| ---| ---| ---|
 | 6 | 2 | 2·2 = 4 ≤ 6 | 2 |
 | 5 | 2 | 4≤5| 2 |

 屏幕总数 = 4，可行。 

现在测试$s = 4$。 

| 类别 x | k | k(s-1) ≤ x? | 贡献 |
 | ---| ---| ---| ---|
 | 6 | 2 | 2·3 = 6 ≤ 6 | 2 |
 | 5 | 2 | 6 ≤ 5（失败）| - |

 这$s$无效。 

所以最好的有效配置产生$3$筛选所有候选人中的最佳选择。 

该跟踪显示了可行性如何消除看似良好的值$s$即使天花板很小。 

### 示例 2

 输入类别：$[1,2,2,2,2,1]$频率：$2 \to 4$,$1 \to 2$， 所以$xs = [4,2]$。 

尝试$s = 2$。 

| x| k | k(s-1) ≤ x | 贡献 |
 | ---| ---| ---| ---|
 | 4 | 2 | 2≤4| 2 |
 | 2 | 1 | 1 ≤ 2 | 1 |

 总计 = 3。 

尝试一下$s = 3$。 

| x| k | k(s-1) ≤ x |
 | ---| ---| ---|
 | 4 | 2 | 4 ≤ 4 |
 | 2 | 1 | 2 ≤ 2 |

 总数再次 = 3。 

这显示了多个有效的$s$可以以相同的最优成本存在。

 ## 边缘情况

 当类别频率远小于候选屏幕尺寸时，就会出现临界边缘情况。 例如，如果$x = 1$和$s = 3$，每个屏幕都有最小尺寸$s-1 = 2$，因此不存在有效分区。 该算法正确地拒绝了这样的$s$因为可行性检查立即失败$k(s-1) > x$。 

另一种边缘情况是频率相差 1 时。假设$x = 5$和$x = 6$同时存在。 候选人$s = 5$给出$k(6)=2$,$k(5)=1$，并且都满足可行性。 该算法既独立处理贡献，又对贡献求和，即使类别在相同条件下表现不同，也能保持正确性。$s$。
