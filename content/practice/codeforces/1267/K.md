 ## 解决方案
 ## 问题理解

 通过将键重复除以从 2 开始的增长除数，将键转换为序列。在每一步都使用除数$i$，我们记录当前数字除以的余数$i$，然后将数字替换为商。 该过程继续进行$i = 2, 3, 4, \dots$直到商变为零。 密钥的指纹被定义为所有这些余数的多重集，这意味着我们忽略它们生成的顺序，只关心每个值出现的次数。 

任务是：给定几个键，确定每个键有多少个其他正整数产生完全相同的余数多重集。 

这些限制迫使我们进行几乎恒定时间的逐键分析。 最多可以有 50,000 个密钥，每个密钥最多$10^{18}$。 任何尝试简单地模拟除法过程的解决方案对于每个数字来说都是可以接受的，因为步骤数量很少，但比较所有整数的指纹是不可能的。 真正的困难不是计算指纹，而是计算有多少个不同的整数对应于相同的指纹结构。 

一个关键的边缘情况是由于忽略顺序而引起的歧义。 例如，两个不同的除法序列可以产生相同的多重集，即使它们的中间商显着不同。 另一个微妙的情况是序列中频繁出现零：一旦商变小，后面的许多除法都会产生零余数，并且这些零在指纹中无法区分。 将位置视为固定的天真的方法会错误地得出独特性的结论。 

关键的结构挑战是指纹来自类似阶乘基的表示，但该问题丢弃了位置信息，将其变成了约束排列计数问题。 

## 方法

 一种直接的方法是模拟给定键的过程，存储余数的完整序列，然后尝试枚举可以生成相同序列的所有整数。 这会立即失败，因为整数是无界的，并且仅根据无序信息无法很好地定义重建候选者。 甚至限制对数字的关注$10^{18}$，暴力破解是完全行不通的。 

关键的观察结果是，该过程相当于将数字写入阶乘系统中。 如果余数是$r_2, r_3, \dots, r_m$，那么原数可以表示为$$k = r_2 \cdot 1! + r_3 \cdot 2! + r_4 \cdot 3! + \cdots + r_m \cdot (m-1)!.$$每个$r_i$满足$0 \le r_i < i$，完全匹配阶乘数字。 

因此，每个数字都唯一对应于一系列有界数字，但指纹会忘记它们的位置。 那么问题就变成了：

 我们得到了多组数字$r_i$，我们必须计算有多少种有效的方法可以将它们分配给位置$i = 2 \dots m$，其中每个位置$i$有能力$i-1$。 

强力解释将尝试所有数字排列并检查有效性、成本$O(n!)$，即使对于$n \approx 20$。 

见解是位置约束具有单调结构。 较小的位置限制较多，因为它们允许的数字值较少。 这创建了一种自然的排序：如果我们按值的递增顺序处理数字，则分配将变为增量，并且仅取决于剩余的槽数，而不是它们的确切身份。 

这将问题简化为在越来越多的可用位置上进行一系列组合选择。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力排列 |$O(n!)$|$O(n)$| 太慢了 |
 | 阶乘数字 DP / 组合数学 |$O(n^2)$每个键|$O(n)$| 已接受 |

 ## 算法演练

 1. 通过模拟除法过程，收集余数，将给定的密钥转换为其阶乘数字表示形式$r_2, r_3, \dots, r_m$。 

步数$m$很小，因为因子增长很快超过$10^{18}$。 
2. 计算每个余数出现的次数。 将该频率数组表示为`cnt[v]`。 
3.让$n$是总位数，意思是$n = m - 1$。 我们在概念上有$n$头寸索引$2 \dots n+1$。 
4. 处理数字值$v = 0, 1, 2, \dots$按递增顺序。 在每一步中，我们决定数字等于$v$被放置。 

关键的限制是这个位置$i$只能承载数字$v$如果$v \le i-1$。 因为我们首先处理较小的值，所以所有对于太小的位置$v$已经被更小的数字填满了。 这确保了每个剩余的空闲位置对于当前值都是有效的。 
5. 目前我们正在处理价值$v$， 确切地$v$位居第一$v$指数已经固定，空闲仓位数量为$n - v$。 
6. 我们选择其中的一个$n - v$空闲位置将被分配数字$v$。 选择数量为：$$\binom{n - v}{\text{cnt}[v]}.$$7. 将这些二项式贡献乘以所有值$v$。 

### 为什么它有效

 处理完所有小于的值$v$, 所有位置$1 \dots v$已被占用，剩余位置形成一个池，每个位置都对数字有效$v$。 该过程从未引入违反约束的情况$r_i < i$，因为较小的索引恰好在其允许的数字范围也耗尽时耗尽。 这保持了“禁止的早期位置”和“已分配的小数字”之间的严格对齐，因此每个组合选择都保持独立和有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXV = 60  # enough since digits are small (m <= ~20)

# precompute factorials up to 60
fact = [1] * (MAXV + 1)
for i in range(1, MAXV + 1):
    fact[i] = fact[i - 1] * i

def nCk(n, k):
    if k < 0 or k > n:
        return 0
    return fact[n] // (fact[k] * fact[n - k])

def fingerprint_counts(x):
    cnt = {}
    i = 2
    while x > 0:
        cnt[x % i] = cnt.get(x % i, 0) + 1
        x //= i
        i += 1
    return cnt, i - 2  # i-2 is number of digits

def solve_one(x):
    cnt, n = fingerprint_counts(x)

    # compress values: we only need values that appear
    max_v = max(cnt.keys(), default=0)

    ans = 1
    for v in range(max_v + 1):
        c = cnt.get(v, 0)
        if c == 0:
            continue
        free = n - v
        if c > free:
            return 0
        ans *= nCk(free, c)
        n -= c

    return ans - 1  # exclude original key itself

t = int(input())
for _ in range(t):
    x = int(input())
    print(solve_one(x))
```该代码首先使用语句中描述的相同除法过程重建基于阶乘的数字多重集。 这`fingerprint_counts`函数执行完全相同的重复除法，确保提取的多重集的正确性。 

然后，组合部分通过迭代数字值来构建答案。 变量`n`跟踪有多少职位尚未分配。 对于每个数字值，我们使用二项式系数计算有多少种方法可以将该数字放置在当前可用的位置中。 我们最后减去原始配置，因为问题要求“其他键”。 

一个微妙的实现细节是`n`当我们分配数字时，它会减少，这反映了这样一个事实：一旦放置了数字值，它就会永久消耗位置。 这使组合模型与阶乘表示的构造性解释保持一致。

 ## 边缘情况

 一个关键的边缘情况是指纹包含许多零。 这些零对应于商已经很小的后期除法，并且它们在多重集中占主导地位。 该算法自然地处理这个问题，因为零像任何其他数字一样被处理，并在组合构造期间被分配给最大的可用位置。 

当所有数字都相同时会出现另一种边缘情况，例如全零的多重集。 在这种情况下，对位置的每次零分配都是等效的，但所有分配都崩溃为单个有效配置，因为二项式链逐步强制执行精确的槽使用。
