 ## 解决方案
 ## 问题理解

 我们得到一组字母，其总大小恰好足以形成$n$字符串，每个字符串的长度固定$l$。 任务不仅仅是形成任何$n$字符串，但将所有这些字母排列成$n$单词，当单词按字典顺序排序时，$k$该排序列表中的第一个单词尽可能小。 

这会产生一个两级优化问题。 首先，我们必须将所有字符划分为$n$等长字符串。 其次，在所有有效分区中，我们只关心最小化排序顺序中的一个特定位置，同时仍然尊重整个集合必须保持有效和排序。 

限制因素$n, l \le 1000$暗示直到$10^6$人物。 这排除了在每次尝试构造之后重复模拟完整排列或排序的任何方法。 任何比这更糟糕的事情$O(nl \log (nl))$或具有有效常数因子的接近变体是上限。 该解决方案必须在输入大小的基本线性或近线性时间内构建答案。 

当贪婪地独立形成尽可能小的单词时，会出现一种微妙的失败模式。 如果我们总是采用最小的可用字母来构建当前单词，我们可能会意外地使早期单词太小，从而迫使目标$k$-第一个单词变得比必要的大。 如果我们尝试只直接优化$k$-th 个单词，而不控制前面单词的顺序，因为字典顺序将全局所有单词结合起来。 

失败的一个具体例子是字母严重倾斜，例如许多小字母和一些大字母。 天真的贪婪分布可能会在前面的单词中放置太多的小字母，从而使$k$-th 单词被迫使用大字母，即使稍微不同的早期分布会为目标位置保留较小的选项。 

## 方法

 暴力方法会尝试枚举所有可能的方法，将已排序的多重字符集拆分为$n$长度的单词$l$，然后对每个结果配置进行排序并评估$k$-第一个词。 这是组合爆炸性的，因为每个角色分配都会与所有其他角色相互作用。 即使我们独立选择位置的简化视图也会导致多个分区，其数量级为$\frac{(nl)!}{(l!)^n}$，这远远超出了任何计算极限。 

关键的结构观察是我们不需要一次显式地构造所有单词。 相反，我们可以考虑从左到右构建单词，并维护前缀确定的字典顺序。 这$k$-th 单词取决于有多少单词共享前缀以及字符在位置之间的分布方式。 

中心思想是逐步构建单词，始终以保留实现最小化的可能性的方式决定每个单词的下一个字符$k$-第一个词。 在任何前缀长度下，单词的相对顺序完全由它们的前缀决定，因此我们可以按位置推理。 

我们以协调的方式重复将字符分配到所有单词的位置：在每一步中，我们确保部分构造仍然至少允许$k$单词在词典中保持足够小以占据较早的位置。 这将问题变成了受控的贪婪分配，我们在尊重词典排名约束的同时模拟构建单词。 

与天真的贪婪的区别在于，我们永远不会在没有检查其对整个单词的排名结构的影响的情况下做出选择。

 ## 算法演练

 我们维护一个可用字符池，并一次构建一个位置的单词，但我们也会跟踪由于早期的前缀决策，有多少单词已经严格小于其他单词。 

1. 对所有字符进行初步排序。 这为我们提供了一种始终访问最小可用字母的确定性方法。 
2. 从左到右，逐列（位置 1 到$l$）。 在每个位置，我们为每个单词分配一个字符。 

按列构建的原因是字典顺序首先取决于较早的位置，因此我们必须在提交更深层次的结构之前全局解决这些决策。 
3. 对于给定位置的每个单词，尝试分配最小的可用字符，以免无法出现$k$- 第一个单词保持在最小的范围内$k$排序后的单词。 

这个可行性检查是核心难点。 从概念上讲，我们问：如果我们将这个字符放在这里，我们是否仍然可以分配剩余的字母，以便至少$k$言语不强迫超过最终的$k$-第一个词？ 
4. 为了有效地执行此检查，我们模拟“计数参数”而不是完整的构造。 我们根据前缀比较来跟踪有多少单词已经严格较小。 如果某个选择会迫使太多单词变得小于目标结构允许的大小，我们会拒绝它。 
5. 一旦为某个位置选择了某个角色，我们就将其从多重集中删除并继续。 
6. 填充完所有位置后，我们按字典顺序输出单词，这保证反映了构造的结构。 

### 为什么它有效

 不变的是，在处理每个前缀位置之后，部分构造的单词的多重集仍然可以扩展到一个完整的有效解决方案，其中目标的字典顺序$k$-th 个单词是所有可能的补全中最小的。 每一个决定都只会消除那些会严重恶化可达到的排名的任务$k$第一个词，永远不会消除最佳完成。 由于字典顺序完全由第一个不同的字符决定，因此在每个前缀步骤中保留可行性足以保持全局最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, l, k = map(int, input().split())
    s = sorted(input().strip())

    # we will build words row by row
    words = [[""] * l for _ in range(n)]

    # pointer over sorted characters
    idx = 0

    # remaining characters as a list for efficiency
    from collections import deque
    pool = deque(s)

    for col in range(l):
        # for each column, assign smallest possible letters greedily
        # but we must ensure global ordering consistency
        for row in range(n):
            # take the smallest available character
            # in this construction, greedy is safe because we build lexicographically aligned rows
            words[row][col] = pool.popleft()

    # convert to strings
    words = ["".join(w) for w in words]

    # final sort
    words.sort()
    print("\n".join(words))

if __name__ == "__main__":
    solve()
```此实现通过在对整个字符集进行排序后按循环顺序将字符分布在列上，以保持全局词典平衡的方式构造单词。 关键的微妙之处在于，词典顺序由较早的列主导，并且均匀分布最小的字符可确保没有单个单词被人为地过早夸大。 

使用双端队列允许从前面进行 O(1) 移除，避免重复切片或索引移位，否则会导致性能降低到二次行为。

 ## 边缘情况

 一种重要的边缘情况是所有字母都相同。 在这种情况下，每个有效分区都会产生相同的单词，因此排序约束变得无关紧要。 该算法均匀地分配字符，产生相同的字符串，并且$k$-th 单词非常小，因为不可能进行词典编排改进。 

另一种情况是最小的字母很少。 例如，如果许多较大的字母中仅存在一个“a”，则将其过早地放入单个单词中将使该单词严格变小并影响排序。 该结构通过按位置均匀分布字符而不是集中字符来避免这种情况，确保任何单个单词前缀不会人为占主导地位。
