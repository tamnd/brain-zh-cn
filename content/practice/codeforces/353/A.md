 ## 解决方案
 ## 问题理解

 我们有一排多米诺骨牌。 每个图块的上半部分和下半部分都有一个数字。 

对于每个图块，我们可以保留其原样，也可以将其旋转 180 度。 旋转图块只是交换其上限值和下限值。 每次旋转花费一秒。 

我们的目标是使这两项总和相等：

 1. 当前上半区所有数字的总和。 
2. 当前下半区所有数字的总和。 

我们必须找到所需的最小旋转次数。 如果没有任何旋转序列可以使两个总和相等，我们输出`-1`。 

瓷砖的数量最多为100块，非常少。 甚至一个$O(n^2)$解决方案在这里是微不足道的。 挑战不在于性能，而在于发现使答案立即得到的奇偶观察。 

关键细节是只有奇偶校验才重要。 数字是 2 还是 6 并不重要，因为两者都是偶数。 同样，1、3 和 5 的行为都相同，因为它们都是奇数。 

如果我们关注实际值而不是奇偶校验，一些边缘情况很容易处理不当。 

考虑：```
1
1 2
```上面的和是奇数，下面的和是偶数。 旋转得到上= 2 和下= 1，所以奇偶性只是交换。 一笔总和永远是奇数。 正确答案是`-1`。 

粗心的解决方案可能会认为，由于一个图块同时包含奇数和偶数，因此旋转总是可以解决问题。 

另一个重要案例是：```
2
1 2
2 1
```最初，两个和都是奇数：

 上= 3，下= 3。 

旋转任一图块都会将两个总和更改为奇数，使两个总和变为偶数。 正确答案是`1`。 

仅检查当前总和是否为偶数的解决方案将错误地返回`-1`。 

还有一个微妙的情况：```
2
1 1
3 3
```上限和下限均为偶数：

 上= 4，下= 4。 

答案是`0`即使每个图块都由两个奇数组成。 一旦达到目标平价，我们就不需要轮换任何东西。 

## 方法

 暴力解决方案将尝试旋转多米诺骨牌的每个子集。 对于每个子集，我们将计算所得的上限和下限总和并检查两者是否为偶数。 由于每张多米诺骨牌都有两个状态，因此有$2^n$可能的配置。 

从概念上讲，这是可行的，因为每个有效的排列都对应于旋转图块的一个子集。 不幸的是，即使对于$n = 100$,$2^{100}$配置是天文数字般巨大，完全无法一一列举。 

我们可以做得更好的原因是平等是唯一重要的事情。 

假设多米诺骨牌包含值$(x, y)$。 旋转它会改变总和的上限$y - x$和较低的总和$x - y$。 

如果$x$和$y$具有相同的奇偶性，那么$y - x$是均匀的。 旋转多米诺骨牌不会改变任一总和的奇偶性。 

如果$x$和$y$有不同的奇偶性，那么$y - x$很奇怪。 旋转多米诺骨牌会同时翻转两个总和的奇偶性。 

这一观察完全说明了问题的特征。 

让：

-$S_u$是当前的总和上限。 
-$S_d$是当前较低的总和。 

如果两个和已经是偶数，答案是`0`。 

如果一个和是偶数，另一个是奇数，则答案立即`-1`。 每次有用的旋转都会同时翻转两个奇偶校验，因此它们始终保持相等。 我们永远无法转身`(even, odd)`进入`(even, even)`。 

如果两个和都是奇数，我们就需要一个奇偶翻转多米诺骨牌，即两个数字具有不同奇偶性的多米诺骨牌。 旋转单张多米诺骨牌使两个总数相等。 如果不存在这样的多米诺骨牌，答案是`-1`。

 | --- | --- | --- | --- |
 | 蛮力 |$O(2^n \cdot n)$|$O(1)$| 太慢了 |
 | 最佳 |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 读取所有多米诺骨牌并计算总上限和总下限总和。 
2. 读取时，检查是否存在两个值具有不同奇偶性的多米诺骨牌。 

这样的多米诺骨牌很特别，因为旋转它会翻转两个总和的奇偶性。 
3. 如果两个和为偶数，则输出`0`。 

不需要轮换，因为目标已经满足。 
4. 如果两个和都是奇数，则检查是否存在奇偶翻转多米诺骨牌。 

如果存在则输出`1`因为旋转一张这样的多米诺骨牌会使两个总和相等。 
5. 如果两个和都是奇数但不存在奇偶翻转多米诺骨牌，则输出`-1`。 

每次旋转都会保持奇偶性，因此奇数总数永远不会变成偶数。 
6. 如果一个和为偶数，另一个为奇数，则输出`-1`。 

任何旋转都会同时改变两个奇偶校验，因此不匹配永远不会消失。 

### 为什么它有效

 关键的不变量是，旋转具有相同奇偶性末端的多米诺骨牌不会改变任何一个总和的奇偶性，而旋转具有不同奇偶性末端的多米诺骨牌会同时翻转两个总数的奇偶性。 

因为两个总数总是一起变化，所以不可能从`(even, odd)`或者`(odd, even)`到`(even, even)`。 这些状态是无法到达的。 

当两个和都是奇数时，单个奇偶翻转多米诺骨牌立即转换`(odd, odd)`进入`(even, even)`，并且一次旋转显然是最小的，因为至少需要进行一次更改。 这耗尽了所有可能的奇偶校验状态，因此该算法是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

upper_sum = 0
lower_sum = 0
has_mixed_parity = False

for _ in range(n):
    x, y = map(int, input().split())
    upper_sum += x
    lower_sum += y

    if (x % 2) != (y % 2):
        has_mixed_parity = True

if upper_sum % 2 == 0 and lower_sum % 2 == 0:
    print(0)
elif upper_sum % 2 == 1 and lower_sum % 2 == 1:
    print(1 if has_mixed_parity else -1)
else:
    print(-1)
```第一部分将两个总和相加。 同时记录任何多米诺骨牌的两半是否具有不同的奇偶性。 

处理完所有输入后，解决方案只需检查两个总计的奇偶性。 

为了清楚起见，检查的顺序稍微重要。 首先处理已经有效的案例，因为它立即给出答案`0`。 这`(odd, odd)`接下来是这种情况，因为这是唯一一次轮换可能有帮助的情况。 其他一切都属于不可能的范畴。 

不存在溢出问题，因为最大可能的总和仅为$100 \times 6 = 600$。

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())

    upper_sum = 0
    lower_sum = 0
    has_mixed = False

    for _ in range(n):
        x, y = map(int, input().split())
        upper_sum += x
        lower_sum += y

        if (x & 1) != (y & 1):
            has_mixed = True

    if upper_sum % 2 == 0 and lower_sum % 2 == 0:
        print(0)
    elif upper_sum % 2 == 1 and lower_sum % 2 == 1:
        print(1 if has_mixed else -1)
    else:
        print(-1)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run("2\n4 2\n6 4\n") == "0", "sample"

# minimum size, impossible
assert run("1\n1 2\n") == "-1", "single tile"

# one rotation solves it
assert run("2\n1 2\n2 1\n") == "1", "odd odd with mixed parity tile"

# odd odd but no mixed parity domino
assert run("2\n1 1\n3 3\n") == "-1", "cannot change parity"

# larger all-equal case
assert run("5\n2 2\n2 2\n2 2\n2 2\n2 2\n") == "0", "already valid"

# maximum-style repeated pattern
inp = "100\n" + "\n".join(["1 2"] * 100) + "\n"
assert run(inp) == "0", "large input"

 ## 边缘情况

 考虑：```
1
1 2
```该算法计算：

 - 上限总和 = 1（奇数）
 - 下总和 = 2（偶数）
 - 存在混合奇偶多米诺骨牌

 总和具有不同的奇偶性，因此算法立即返回`-1`。 

旋转图块会改变状态`(odd, even)`到`(even, odd)`。 不匹配仍然存在。 输出是正确的。

 由于两个总数都是奇数并且存在奇偶校验改变多米诺骨牌，因此算法返回`1`。 

旋转任一图块都会将两个总数翻转为偶数。 一步就足够了，而且是最少的。
