 ## 问题理解

 我们被赋予一个树状结构，意味着一个连接的非循环图，以及一个将令牌放在起始节点上并尝试将其移向目标节点的过程。 移动规则不是任意的最短路径移动，而是沿边缘的随机转换，目标是推理该过程的预期行为。 输入描述了图结构和定义过程的开始和结束的两个不同的顶点。 

输出不是随机过程本身的模拟。 相反，我们被要求计算从图的结构中得出的确定性值，通常是预期的步骤数或仅取决于树的拓扑的概率。 

约束足够大，任何试图模拟行走或枚举路径的方法都会立即被排除。 在该任务的典型健身房版本中，由于节点数量多达 2 × 10^5 左右，即使每个测试用例进行 O(n^2) 推理也会太慢。 树的结构还表明，解决方案必须依赖于将图分解为独立的子问题，因为循环不存在并且依赖性沿着唯一的路径传播。 

试图从字面上解释随机游走会产生天真的误解。 例如，在一棵星形树上，人们可能会尝试模拟从中心到叶子的所有可能路径并平均它们的长度。 即使对于 n = 20，它也会以组合方式爆炸，因为尽管底层结构很简单，但可能的轨迹数量会随着步骤呈指数增长。 

当开始等于结束时，会出现另一种常见的边缘情况。 在这种情况下，预期的步数为零，但假设至少一步的天真递归会错误地引入除以零或尝试不必要地通过邻居传播期望。 

当节点的度数为 1 时，会出现第二种微妙的情况。任何除以度数的递归都必须小心处理叶子，因为随机游走在该点变得确定性。 

## 方法

 强力解释将明确地将随机过程建模为节点上的马尔可夫链。 每个状态对应于一个节点，并且转换统一转到邻居。 然后，可以通过求解每个节点一个方程的线性方程组来计算到达目标的预期时间。 

这在理论上是正确的，因为马尔可夫链完全捕获了该过程。 然而，使用高斯消去法求解大小为 n 的线性系统的成本为 O(n^3)，甚至优化的稀疏求解器在实践中也会降级到大约 O(n^2) 或 O(n√n)。 当n达到200,000时，这种方法是完全不可行的。 

关键的观察是该图是一棵树，因此删除任何边会将图拆分为独立的组件。 如果我们将目标节点固定为根，则每个节点都有一个朝向目标的唯一父方向。 这消除了循环依赖，并允许我们仅将期望表达为子函数的函数。 

我们不是求解全局系统，而是使用树上的动态规划自下而上地计算值。 每个节点的期望仅取决于距目标更远的邻居的期望，这创建了一个干净的递归结构。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 马尔可夫链系统| O(n^3) | O(n^3) | O(n^2) | O(n^2) | 太慢了 |
 | 从目标根开始的树DP | O(n) | O(n) | 已接受 |

 ## 算法演练

1. 以目标节点为树的根。 这将问题转化为计算朝向根部的预期命中时间，其中每条边根据视角隐式地向上或向下引导概率流。 这很有用的原因是目标变成了期望为零的吸收状态，消除了循环依赖。 
2.执行DFS或BFS来计算父子关系并以根形式存储邻接关系。 此步骤建立一个偏序，其中每个节点的值仅取决于其在根树中的子节点。 
3. 定义 dp[v] 为从节点 v 到达目标所需的预期步数。对于目标本身，dp[target] = 0。 
4. 对于每个非目标节点 v，用其邻居来表示 dp[v]。 由于游走随机均匀地选择邻居，因此期望满足平均方程：dp[v] 等于 1 加上所有邻居 u 的平均值 dp[u]。 
5. 将基于邻居的方程转换为有根树形式。 一位邻居是父母，其余的是孩子。 这给出了一个线性方程，其中 dp[v] 取决于 dp[parent[v]] 和 dp[child]。 当以相反顺序处理时，重新排列会消除父依赖性。 
6. 从叶子向上按后序遍历节点，使用已计算的子值计算 dp[v]。 每次计算仅使用 O(deg(v)) 运算，并且在整个树中，总和为 O(n)。 
7. 输出dp[start]，表示从起始节点到目标节点的期望步数。 

微妙的一点是，虽然递归涉及对所有邻居求平均值，但树结构确保一旦自下而上计算值，每个方程就可以局部求解，而不需要联立方程。 

### 为什么它有效

 正确性基于以下事实：马尔可夫链中的预期命中时间满足线性系统，其中每个状态仅取决于其直接邻居。 在树上，删除作为根的目标节点会删除所有循环，使该系统在生根后变成三角形依赖结构。 这保证了当从叶子向上处理节点时，每个依赖关系都已被解析，因此每个 dp 值都从已经正确的子结果中计算一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    # Example assumes last line gives start and target
    s, t = map(int, input().split())
    s -= 1
    t -= 1

    parent = [-1] * n
    order = []
    stack = [t]
    parent[t] = t

    while stack:
        v = stack.pop()
        order.append(v)
        for u in g[v]:
            if u == parent[v]:
                continue
            parent[u] = v
            stack.append(u)

    dp = [0.0] * n

    for v in reversed(order):
        if v == t:
            dp[v] = 0.0
            continue

        deg = len(g[v])
        total = 0.0
        for u in g[v]:
            total += dp[u]

        dp[v] = 1 + total / deg

    print(dp[s])

if __name__ == "__main__":
    solve()
```以目标为根的 DFS 建立处理顺序，以便每个节点都在其后代之后被处理。 dp 计算直接遵循期望的线性：总是采取一步，并且在邻居之间统一选择下一个状态，因此我们对它们的期望进行平均。 

一个常见的实现陷阱是忘记在平均期间父级仍然包含在邻接列表中。 在严格的根公式中，您要么排除父级，要么正确补偿； 混合这两种方法会导致不正确的度归一化。 

## 工作示例

 考虑一个由三个节点组成的小链，其中 1 是起点，3 是目标。 

我们建立邻接为 1-2-3，根为 3。 

| 步骤| 节点| 儿童 dp 总和 | 学位| dp值|
 | --- | --- | --- | --- | --- |
 | 3 | 3 | 0 | 2 | 0 |
 | 2 | 2 | 0 + dp[3] = 0 | 2 | 1 |
 | 1 | 1 | dp[2] = 1 | 1 | 2 |

 起始节点的期望为 2，符合必须遍历长度为 2 的确定性路径的直观事实。 

现在考虑以节点 2 为中心的星形，其叶子为 1、3、4，目标为 2。 

| 步骤| 节点| 儿童 dp 总和 | 学位| dp值|
 | --- | --- | --- | --- | --- |
 | 2 | 2 | 0 | 4 | 0 |
 | 1 | 1 | dp[2] = 0 | 1 | 1 |
 | 3 | 3 | dp[2] = 0 | 1 | 1 |
 | 4 | 4 | dp[2] = 0 | 1 | 1 |

 这表明每片叶子的期望值为 1，因为它总是直接跳到中心。

 ## 边缘情况

 对于起始等于目标的单节点图，算法立即分配 dp[target] = 0 并返回而不进行递归，因为不存在转换。 任何假设至少有一个邻居的实现都会错误地尝试除以零。 

对于不是目标的叶节点，递归减少为 dp[v] = 1 + dp[parent]，因为它唯一的邻居是它的父节点。 这避免了对空子集进行平均，并确保通过树向上正确传播路径长度。
