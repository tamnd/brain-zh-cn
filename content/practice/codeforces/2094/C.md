 ## 解决方案
 ## 问题理解

 我们被赋予了一个$n \times n$由未知排列生成的网格$p$长度$2n$。 

构造规则很简单：单元格中的值$(i,j)$是$p_{i+j}$。 自从$i$和$j$从 1 开始，同一反对角线上的每个单元格具有相同的值，因为它们共享相同的总和$i+j$。 

我们的任务是重建整个排列$p_1,p_2,\dots,p_{2n}$。 

关键的观察结果是网格仅包含有关索引的信息$2$通过$2n$。 价值$p_1$永远不会出现，因为最小的可能总和是$1+1=2$。 

限制非常小。 全部的总和$n$跨测试用例最多$800$，因此即使读取输入也主导了工作。 任何扫描一次网格的解决方案都足够快。 不需要复杂的数据结构或优化。 

一个不明显的边缘情况是$n=1$。 

输入：```
1
1
1
```网格仅包含$p_2=1$。 由于排列必须包含数字$1$和$2$，缺失值是$2$。 答案是：```
2 1
```粗心的解决方案可能会假设每个排列位置出现在网格中的某个位置并且忘记重建$p_1$。 

Another subtle case is when the missing value is neither the smallest nor the largest number.

 输入：```
1
2
2 3
3 4
```我们从网格中恢复$p_2=2$,$p_3=3$,$p_4=4$。 唯一的号码来自$\{1,2,3,4\}$没有出现的是$1$， 所以：```
1 2 3 4
```任何猜测的方法$p_1$从网格结构而不是使用排列属性在这里会失败。 

## 方法

 思考问题的一种暴力方式是重建每个位置$p_k$通过检查所有索引满足的单元格$i+j=k$。 由于保证网格有效，因此每个这样的单元格都包含相同的值。 收集后$p_2$通过$p_{2n}$，我们确定剩余的数字并将其放置在位置$1$。 

这已经在限制范围内起作用了。 网格仅包含$n^2$细胞，和$n \le 800$。 

真正的见解是我们不需要单独检查每个反对角线。 

对于任何金额$s$之间$2$和$2n$，总是至少有一个有效单元格$i+j=s$。 由于该反对角线上的所有单元都包含$p_s$，单个代表单元就足够了。 

为了$s \le n+1$，我们可以使用单元格$(1,s-1)$。 

为了$s > n+1$，我们可以使用单元格$(s-n,n)$。 

这立即给出了所有值$p_2,p_3,\dots,p_{2n}$。 自从$p$是一个排列$1$通过$2n$，这些恢复值中恰好缺少一个数字。 那个缺失的号码一定是$p_1$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(n)$| 已接受 |
 | 最佳 |$O(n^2)$|$O(n)$| 已接受 |

 渐近复杂度是相同的，因为读取网格已经花费了$O(n^2)$，但最优方法直接提取每个排列值。 

## 算法演练

 1. 读取网格。 
2. 创建数组`p`长度`2n + 1`使用从 1 开始的索引。 
3. 对于每一笔金额`s`从`2`到`2n`， 恢复`p[s]`。 

如果`s <= n + 1`， 使用`grid[0][s - 2]`，对应于单元格`(1, s-1)`。 

否则，使用`grid[s - n - 1][n - 1]`，对应于单元格`(s-n, n)`。 

两个单元格都位于反对角线上，总和为`s`，所以它们恰好包含`p[s]`。 
4. 标记所有恢复的值`p[2] ... p[2n]`。 
5. 数字之中`1 ... 2n`，找到从未标记过的那个。 
6. 将该数字设置为`p[1]`。 
7. 输出`p[1] ... p[2n]`。 

### 为什么它有效

 每个反对角线恰好对应一个排列位置。 与和的反对角线$s$仅包含值$p_s$，因此从该反对角线中取出任何单元格即可恢复正确的排列元素。 

网格涵盖总和$2$通过$2n$，这意味着它揭示了除$p_1$。 由于该序列保证是一个排列$1$通过$2n$，恢复值中恰好缺少一个数字。 那个缺失的号码一定是$p_1$。 没有其他选择是可能的，这就是重建是独一无二的原因。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    g = [list(map(int, input().split())) for _ in range(n)]

    p = [0] * (2 * n + 1)

    for s in range(2, 2 * n + 1):
        if s <= n + 1:
            p[s] = g[0][s - 2]
        else:
            p[s] = g[s - n - 1][n - 1]

    seen = [False] * (2 * n + 1)
    for i in range(2, 2 * n + 1):
        seen[p[i]] = True

    for x in range(1, 2 * n + 1):
        if not seen[x]:
            p[1] = x
            break

    print(*p[1:])
```第一部分完全按照给定的方式读取网格。 

循环结束`s`重建位置`2`通过`2n`。 索引是唯一稍微棘手的部分。 输入网格存储有从 0 开始的索引，因此 cell`(1, s-1)`变成`g[0][s-2]`，而细胞`(s-n, n)`变成`g[s-n-1][n-1]`。 

恢复所有可见的排列值后，代码将它们标记在`seen`大批。 由于排列包含来自`1`到`2n`恰好一次，扫描未标记的数字立即产生`p[1]`。 

不存在整数溢出问题，因为所有值最多都是`1600`。

 ## 边缘情况

 考虑最小的有效输入：```
1
1
1
```该算法仅恢复`p2 = 1`。 排列必须包含数字`{1,2}`。 缺失值是`2`，所以它输出：```
2 1
```即使网格由单个单元组成，重建仍然有效。 

现在考虑：```
1
2
2 3
3 4
```恢复给出：```
p2 = 2
p3 = 3
p4 = 4
```缺失的号码来自`{1,2,3,4}`是`1`，生产：```
1 2 3 4
```这证实了该算法不依赖于缺失值的任何特殊位置。 

最后，考虑：```

```回收率：```

p3 = 4
p4 = 2
```唯一未使用的号码是`3`， 所以：```

```这验证了隐藏的第一个元素可以是排列范围内的任何值，而不仅仅是端点。
