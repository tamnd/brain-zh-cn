 ## 解决方案
 ## 问题理解

 这个问题中的程序是一个非常小的人造机器。 它有一个 8 位寄存器`r`，因此寄存器只能包含来自`0`到`255`。 执行从第一条指令开始`r = 0`。 每条指令要么更改寄存器并移至下一条指令，要么检查寄存器并可能跳转至另一条指令。 仅当执行越过最后一条指令时，程序才会停止。 

任务是决定给定的程序是否最终到达这个停止点，或者是否继续永远执行。 

约束是围绕语言的特殊结构设计的。 一个正常的程序可能最多有`10^4`指令，所有测试用例的指令总数最多为`10^5`。 一般来说，在未知的时间内模拟任意程序是不可能的，但这种语言具有有界的状态空间。 当前指令可以有`n + 1`可能的位置，寄存器只有 256 个可能的值。 这最多给出了`256 * n`不同的执行状态。 为了`n = 10^4`，大约有 256 万个州，小到足以访问一次。 

主要的边缘情况是循环而不更改寄存器的程序。 例如：```
2
add 0
beq 0 1
```正确的输出是：```
No
```在第一条指令之后，寄存器仍然为零。 第二条指令永远跳回到第一条指令。 没有循环检测的简单模拟将永远无法完成。 

另一种情况是循环最终到达新状态，因为寄存器回绕。 例如：```
3
add 252
add 1
bgt 252 2
```正确的输出是：```
Yes
```该寄存器是 8 位的，因此在达到 255 后，它会回绕为 0。将寄存器视为无限整数的解决方案会错误地认为该值不断增加并错过停止路径。 

第三个常见错误是忽略指令指针是状态的一部分这一事实。 考虑：```
3
add 1
bne 252 1
beq 252 1
```正确的输出是：```
No
```仅寄存器值不足以检测重复。 不同指令中的相同寄存器值代表不同的未来行为。 

## 方法

 直接的方法是逐条指令执行程序。 如果执行到指令`n + 1`，程序停止，答案是`Yes`。 如果执行永远持续下去，这个模拟将永远不会终止，所以我们需要一种方法来识别无限运行。 

暴力版本只能运行程序任意数量的步骤。 这是不正确的，因为有效的程序在停止之前可能需要更多步骤。 最坏的情况可以包含一切可能`(instruction, register)`重复之前的状态，这取决于`256 * n`州。 和`n = 10^4`，这大约是 256 万个转换，因此完全有界模拟就足够了，但无界模拟则不够。 

关键的观察结果是这台机器是确定性的。 一旦我们知道当前指令和寄存器值，下一个状态就完全确定了。 有限数量状态上的确定性过程必须达到停止状态或最终重新访问某个状态。 重新访问状态意味着相同的未来执行将永远重复。 

观察到状态空间是有限的，我们可以将问题简化为隐式图上的图遍历。 我们不需要构建图表。 我们只需要记住在遵循单一执行路径时已经出现了哪些状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 无界| O(1) | O(1) | 不正确，因为无限循环永远不会结束 |
 | 最佳 | O(256n) | O(256n) | O(256n) | O(256n) | 已接受 |

 ## 算法演练

 1. 以方便的方式存储每条指令。 一个`add`指令仅存储其值，而分支指令则存储其条件、目的地和类型。 
2. 从指令开始执行`0`与寄存器值`0`。 使用按指令位置和寄存器值索引的访问表。 
3. 执行指令前，检查当前是否存在`(instruction, register)`对已经被访问过。 如果是的话，机器就会重复之前的情况，所以程序永远不会停止。 
4. 将当前状态标记为已访问并执行指令。 对于算术指令，请使用模 256 更新寄存器，因为寄存器只有 8 位。 
5. 对于分支指令，将寄存器与存储的值进行比较。 如果条件为真，则跳转到目标指令。 否则，继续执行下一条指令。 
6. 重复直到任一指令`n + 1`已达到或发现重复状态。 

这样做的原因是执行是确定性的。 状态完全由正在执行的指令和当前寄存器值描述。 如果相同的状态出现两次，则接下来的每个转换也将是相同的，从而形成无限循环。 如果没有状态重复，则执行最终必须通过到达停止位置来离开有限状态空间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        prog = []

        for _ in range(n):
            parts = input().split()
            if parts[0] == "add":
                prog.append(("add", int(parts[1])))
            else:
                prog.append((parts[0], int(parts[1]), int(parts[2]) - 1))

        visited = [[False] * 256 for _ in range(n)]
        pc = 0
        r = 0

        while pc < n:
            if visited[pc][r]:
                ans.append("No")
                break

            visited[pc][r] = True
            ins = prog[pc]

            if ins[0] == "add":
                r = (r + ins[1]) % 256
                pc += 1
            else:
                op, v, k = ins
                ok = False

                if op == "beq":
                    ok = (r == v)
                elif op == "bne":
                    ok = (r != v)
                elif op == "blt":
                    ok = (r < v)
                elif op == "bgt":
                    ok = (r > v)

                if ok:
                    pc = k
                else:
                    pc += 1
        else:
            ans.append("Yes")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```程序表示将操作名称与该操作所需的参数放在一起。 跳转目标会立即转换为从零开始的索引，从而避免在模拟过程中重复减一。 

这`visited`数组每条指令占一行，所有可能的寄存器值有 256 列。 寄存器更新使用`% 256`因为 8 位寄存器溢出会丢弃高位。 

循环在执行指令之前检查重复状态。 执行后检查也可以，但执行前检查使不变量更清晰：到达执行点的每个状态要么被处理一次，要么被检测为一个循环。 

Python 整数不会溢出，因此不需要对计数器或索引进行特殊处理。

 ## 边缘情况

 处理未更改的寄存器无限循环是因为状态`(instruction, register)`立即重复。 为了：```
2
add 0
beq 0 1
```各州`(1,0)`和`(2,0)`被反复访问。 什么时候`(1,0)`再次出现，算法输出`No`而不是永远模拟。 

通过将每个值保持在范围内来处理寄存器溢出`0`到`255`。 为了：```
3
add 252
add 1
bgt 252 2
```寄存器序列最终从`255`到`0`。 该算法查看实际的机器行为并到达停止指令。 

通过将指令索引存储为状态的一部分来处理相同寄存器值出现在不同指令中的情况。 仅寄存器访问集会过早错误地报告周期，因为具有相同寄存器值的两条指令可能具有不同的未来。 这对`(program counter, register)`是完整的机器状态，因此算法仅在真正执行重复时停止。
