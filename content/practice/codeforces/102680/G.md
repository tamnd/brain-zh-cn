 ## 解决方案
 ## 问题理解

 该问题描述了一个连接的无向道路网络。 每个交叉路口都是一个顶点，每条道路都是一条边。 三名赛车手想要选择起始交叉点和终点交叉点。 由于每个赛车手总是选择这两点之间的最短路径，因此比赛路线被迫成为所选对的最短路径之一。 目标是选择最短路径尽可能长的一对交叉点。 

用图的术语来说，我们需要找到任意两个顶点之间的最大最短路径距离。 该值是图形的直径。 答案计算的是走过的道路，而不是走过的十字路口的数量。 包含五个交叉点的路径的长度为四，因为它使用四条道路。 

输入包含多个测试用例。 每个测试用例给出了交叉口和道路的数量，后面是无向道路连接。 该图保证是连通的，因此每个交点都可以到达其他每个交点。 

这些限制足够小，足以允许算法的顶点数量约为二次或略高。 由于所有测试用例的交集总数最多为 1000 个，并且每个单独的图最多有 500 个交集，因此从每个顶点运行广度优先搜索是实用的。 尝试独立枚举所有顶点对和搜索路径的解决方案会重复大量工作并且变得不必要的昂贵。 

在几种边缘情况下，不正确的实现可能会失败。 具有一个交点和一个自环的图在不同点之间不需要移动，因此答案为零。```
1
1 1
1 1
```正确的输出是：```
0
```将答案初始化为一个或假设每条路径至少包含一条道路的解决方案将产生错误的结果。 

最长最短路径不是看起来简单的链的图表是另一个常见错误。 例如：```
1
4 4
1 2
2 3
3 4
1 4
```正确的输出是：```
2
```从1到4的直接道路可以防止直径变成3。 如果粗心地搜索最长可能步行而不是最长最短路径，则会错误地选择路径 1-2-3-4。 

平行路和自环路，如无特殊情况也需要处理。 它们不会改变两个交叉路口之间的最短距离，因为每条道路的成本相同。 BFS 实现自然会忽略重复的边和自循环。 

## 方法

 直接的暴力解决方案将考虑每对交叉点。 对于每一对，它将运行最短路径算法来找到它们的距离，然后保留找到的最大值。 由于图是未加权的，BFS 对于每个最短路径查询来说就足够了。 和$n$顶点，有$O(n^2)$对，每个 BFS 成本$O(n+m)$，给出总复杂度$O(n^2(n+m))$。 和$n=500$，这已经是每个测试用例大约 1.25 亿个顶点边缘处理单元，并且它重复了可以避免的工作。 

关键的观察结果是，可以立即计算从一个起始交叉路口到每个其他交叉路口的最短距离。 BFS 逐层探索图，因此经过一次 BFS 我们就知道从一个顶点到所有其他顶点的距离。 由于该图未加权，因此不需要 Dijkstra 或重复的成对搜索。 

最佳方法是在每个交叉点运行一次 BFS。 每个 BFS 给出距该源的所有距离，其中的最大值是直径的候选值。 对所有源进行最大候选即可给出答案，因为当其端点之一用作 BFS 源时，每个可能的对都会出现。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²(n+m)) | O(n²(n+m)) | O(n+m) | 太慢了 |
 | 最佳 | O(n(n+m)) | O(n(n+m)) | O(n+m) | 已接受 |

 ## 算法演练

 1. 为每个路口建立邻接表。 每条道路都在两个方向上添加，因为任一方向都允许移动。 
2. 从每个路口运行 BFS。 在 BFS 期间，存储从所选源到每个其他交叉路口的最短距离。 
3. 每次 BFS 完成后，检查从该源达到的最大距离并更新全局最大值。 该值表示从当前路口出发的最长最短路线。 
4. 当所有路口都被用作 BFS 源后，输出最大记录距离。 每一个可能的起点和终点对都已通过其中一次 BFS 运行进行了考虑。 

为什么它有效：

 该算法背后的不变性是，在从某个顶点进行 BFS 后，每个存储的距离都是从该顶点到相应目的地的最短可能道路数。 BFS 具有此属性，因为它按照距离递增的顺序访问顶点。 由于每个顶点都用作源，因此每对交点的最短距离至少计算一次。 所有这些最短距离中的最大值正是图形直径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def bfs(start, graph):
    n = len(graph)
    dist = [-1] * n
    dist[start] = 0
    queue = [start]
    head = 0

    while head < len(queue):
        u = queue[head]
        head += 1
        for v in graph[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                queue.append(v)

    return max(dist)

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, m = map(int, input().split())
        graph = [[] for _ in range(n)]

        for _ in range(m):
            a, b = map(int, input().split())
            a -= 1
            b -= 1
            graph[a].append(b)
            graph[b].append(a)

        diameter = 0
        for i in range(n):
            diameter = max(diameter, bfs(i, graph))

        ans.append(str(diameter))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```邻接表可以有效地存储图，因为每条道路在每个方向上都会被处理一次。 BFS 函数使用列表作为队列和索引一起使用，而不是重复删除第一个元素，避免了类似操作的线性成本`pop(0)`。 

距离数组开始于`-1`，它代表尚未到达的路口。 当 BFS 找到未访问的邻居时，它会将父节点的距离加一。 由于 BFS 是分层扩展的，因此第一个分配的距离始终是最短的距离。 

外循环从每个交叉点运行 BFS。 任何 BFS 返回的最大距离就是最终直径。 该图保证是连通的，因此每个 BFS 都到达所有顶点并且`max(dist)`始终有效。 

Python 整数不会溢出，最大队列大小受交集数量的限制。 该实现还避免了递归，从而消除了递归深度问题的任何风险。

 ## 边缘情况

 仅具有自循环的单个交叉点可以正确处理，因为 BFS 从距离零开始并且永远不会发现更远的顶点。 最大距离保持为零，符合无需行驶任何道路的事实。```
1
1 1
1 1
```BFS 队列仅包含起始交叉点。 自循环指向已经访问过的顶点，因此距离数组保持不变`[0]`。 

包含捷径的图表需要使用最短距离，而不是最长的可能路线。 在示例中：```
1
4 4
1 2
2 3
3 4
1 4
```从交叉点 1 开始的 BFS 给出距离`[0,1,2,1]`。 通过 2 和 3 的路线存在，但它不是到 4 的最短路线，因为直接边 1-4 更短。 该算法将距离 2 记录为最大值，这是正确的。 

平行道路和自环路不需要额外处理。 BFS只关心邻居是否已经被访问过。 多个相同的边仍然会产生相同的最短距离，并且自循环不能减少已知的距离。
