 ## 解决方案
 ## 问题理解

 该问题描述了一系列位置，编号为`1`到`n`。 某些位置范围被消除，这意味着它们不能包含丢失的对象。 删除所有给定范围后，仅保留一个位置。 任务是找到剩下的位置。 

输入给出位置总数和消除范围的数量，然后是每个消除区间的开始和结束。 间隔可能会重叠，因此同一位置可以被删除多次。 输出是从未包含在任何间隔中的单个位置。 原来的约束条件允许`n`一样大`2,000,000,010`和最多的间隔数`1000`，因此迭代每个位置是不可能的。 所有位置的循环将需要数十亿次操作，而间隔的数量足够小，以至于主要取决于间隔的算法是预期的方向。 

直接模拟还存在隐藏的内存问题。 创建一个长度数组`n`标记删除的位置是不可能的，因为`n`可能在二十亿左右。 该解决方案必须仅适用于给定的间隔及其之间的间隙。 

第一个边缘情况是答案位于每个删除的范围之前。 例如：```
10 1
3 10
```正确的输出是：```
1
```仅检查间隔对之间的间隙的粗心方法会错过第一个间隔之前的前缀。 

第二种边缘情况是答案位于每个删除的范围之后：```
10 1
1 9
```正确的输出是：```
10
```忘记在最后一个间隔之后检查后缀的实现将在这里失败。 

第三种边缘情况是重叠间隔：```
10 3
3 5
5 8
7 10
```正确的输出是：```
1
```如果独立处理间隔而不合并或跟踪最远的覆盖位置，则重叠范围可能会产生实际不存在的假间隙。 

## 方法

 蛮力的想法很简单。 创建所有位置的表示`1`到`n`，将每个间隔内的每个位置标记为已删除，并扫描唯一剩余的位置。 这是正确的，因为它直接遵循答案的定义。 

问题是值`n`。 在最大的情况下，仅扫描就需要大约二十亿次操作，而存储数组则需要数十亿个条目。 即使在考虑间隔更新之前，表示本身也太大了。 

有用的观察是，与坐标范围相比，间隔的数量很小。 删除的位置仅由描述`u`间隔，其中`u`至多是`1000`。 我们可以查看覆盖范围发生变化的地方，而不是查看每个位置。 

如果我们按起始位置对间隔进行排序并合并重叠的间隔，则每个合并的间隔代表一个连续的已删除位置块。 丢失的对象必须位于两个合并间隔之间的间隙内，或者在第一个间隔之前，或者在最后一个间隔之后。 由于保证存在一个未被覆盖的位置，因此找到该间隙就足够了。 

蛮力之所以有效，是因为每个单独的位置都会被检查，但会失败，因为坐标空间巨大。 只有区间边界很重要的观察结果让我们可以将问题的大小减少到`n`到间隔数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n + 总覆盖长度) | O(n) | 太慢了 |
 | 最佳 | O(u log u) | O(u log u) | O(u) | 已接受 |

 ## 算法演练

 1. 读取所有区间并按其左端点对它们进行排序。 排序将彼此靠近的间隔放置在一起，从而可以通过单遍进行重叠检测。 
2. 合并排序后的区间。 保留当前覆盖的段。 如果下一个间隔在当前段之前或结尾处开始，则如有必要，请延长当前段。 否则，两段之间就会有间隙。 
3.在接受第一个合并区间之前，检查它是否在position之后开始`1`。 如果是，则其之前的每个位置都将被揭开，并且由于只有一个有效位置，因此该位置就是答案。 
4. 处理完所有间隔后，检查连续合并间隔之间的间隙。 如果一个合并间隔结束于`a`下一个开始于`b`，然后从每个位置`a + 1`到`b - 1`被揭开。 由于只剩下一个位置，`a + 1`就是答案。 
5. 如果没有找到更早的间隙，则剩余的可能性是最后合并间隔之后的后缀。 答案是结束后的一个位置。 

为什么它有效：

 合并后，每个移除的位置都属于一个合并的线段，并且两个合并的线段不会重叠或接触。 这意味着不在这些细分市场内的每个职位都是真正可用的。 该算法会检查可能存在此类位置的每个可能区域：前缀、段之间的每个间隙以及后缀。 由于输入保证了恰好一个可用位置，因此找到的第一个未覆盖位置必定是所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, u = map(int, input().split())
    intervals = []

    for _ in range(u):
        l, r = map(int, input().split())
        intervals.append((l, r))

    if u == 0:
        print(1)
        return

    intervals.sort()

    merged = []
    cur_l, cur_r = intervals[0]

    for l, r in intervals[1:]:
        if l <= cur_r + 1:
            if r > cur_r:
                cur_r = r
        else:
            merged.append((cur_l, cur_r))
            cur_l, cur_r = l, r

    merged.append((cur_l, cur_r))

    if merged[0][0] > 1:
        print(1)
        return

    for i in range(len(merged) - 1):
        left_end = merged[i][1]
        right_start = merged[i + 1][0]
        if right_start - left_end > 1:
            print(left_end + 1)
            return

    print(merged[-1][1] + 1)

if __name__ == "__main__":
    solve()
```代码首先仅存储间隔，而不存储单个位置。 这使得内存与范围的数量成比例。 

合并循环维护一个段`[cur_l, cur_r]`代表所有当前已知的已删除的连接位置。 当下一个间隔在此段内部或直接在该段之后开始时，扩展右端点可以保持表示的紧凑性。 这`+1`在`l <= cur_r + 1`是故意的，因为接触间隔在它们之间没有留下未被覆盖的位置。 

合并后，按坐标顺序执行检查。 前缀检查处理第一个删除的段之前的答案。 循环检查内部间隙。 最终打印处理最后删除的段之后的后缀。 因为答案肯定存在，所以最后一行始终打印有效位置。 

Python 整数不会溢出，因此较大的值`n`不需要特殊处理。 该实现还避免了递归并且仅使用一小部分间隔。 

## 工作示例

 ### 示例 1

 输入：```
10 3
7 10
1 1
3 8
```排序后：

 | 步骤| 当前间隔 | 合并间隔 | 行动|
 | --- | --- | --- | --- |
 | 1 | (1, 1) | []| 开始第一段 |
 | 2 | (3, 8) | []| 创建单独的段 |
 | 3 | (7, 10) | [(1,1),(3,10)] | 合并重叠|

 之间的差距`(1,1)`和`(3,10)`是位置`2`，所以答案是：```
2
```该跟踪显示了为什么必须合并重叠间隔。 间隔`(3,8)`和`(7,10)`不是单独的删除区域。 

### 示例 2

 输入：```
2000000010 2
1 8
10 2000000010
```合并的间隔已经是：

 | 步骤| 当前间隔 | 合并间隔 | 行动|
 | --- | --- | --- | --- |
 | 1 | (1,8) | []| 开始第一段 |
 | 2 | (10,2000000010) | [(1,8)] | 创建第二段 |

 差距在于位置之间`9`和`9`，所以答案是：```
9
```这表明该算法可以处理非常大的坐标，而无需根据`n`。

import sys
import io

def solve_case(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline

    n, u = map(int, data().split())
    intervals = []

    for _ in range(u):
        intervals.append(tuple(map(int, data().split())))

    if u == 0:
        ans = 1
    else:
        intervals.sort()
        merged = []
        l, r = intervals[0]

        for nl, nr in intervals[1:]:
            if nl <= r + 1:
                r = max(r, nr)
            else:
                merged.append((l, r))
                l, r = nl, nr

        merged.append((l, r))

            ans = 1
        else:

                if merged[i + 1][0] - merged[i][1] > 1:
                    ans = merged[i][1] + 1
                    break

    sys.stdin = old_stdin
    return str(ans)

 ## 边缘情况

 对于前缀情况：```
10 1
3 10
```合并后的列表仅包含`(3,10)`。 第一个合并间隔不从位置开始`1`，所以算法立即返回`1`。 基于扫描的解决方案在这里可以工作，但基于间隔的解决方案必须明确处理此边界。 

对于后缀情况：```
10 1
1 9
```合并后的列表是`(1,9)`。 没有内部间隙，因此最终检查返回`9 + 1 = 10`。 这捕获了仅检查间隔之前或间隔之间的空间的解决方案。 

对于重叠间隔：```
10 3
3 5
5 8
7 10
```排序后的区间合并为`(3,10)`。 该算法从不将重复覆盖视为创建额外的空闲位置。 由于前缀未被覆盖，因此它返回`1`，这是唯一有效的答案。
