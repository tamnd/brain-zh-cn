 ## 问题理解

 输入是通过获取原始单词序列然后插入标记字符串而形成的单个字符串`"WUB"`以一种非常具体的方式围绕它们和它们之间。 每个原创单词保证不包含`"WUB"`在它里面，所以每次出现`"WUB"`最终的字符串是在混音过程中添加的人工结构。 

任务是恢复原始的单词序列。 从概念上讲，我们需要对待`"WUB"`作为可能重复出现并且可能出现在块中的分隔符。 删除这些分隔符后，剩余的字符应按顺序组成原始单词，并用单个空格分隔。 

字符串长度最多为 200，这立即排除了对繁重预处理或复杂解析策略的任何担忧。 即使 O(n²) 解决方案也是安全的，但结构表明线性扫描就足够了。 

一些边缘情况对于正确性很重要。 第一的，`"WUB"`可以连续出现，产生长串分隔符，例如`"WUBWUBWUB"`，其行为应该类似于单个分隔符而不是多个空单词。 例如，`"WUBWUBABC"`应该产生`"ABC"`并且不包括空标记。 

第二，`"WUB"`可以出现在字符串的开头或结尾，不应产生前导或尾随空格。 例如，`"WUBABCWUB"`仍应输出`"ABC"`没有额外的空白。 

第三，字符串可能只包含一个单词，而不包含任何单词`"WUB"`根本没有，在这种情况下，输出是原始字符串不变。 

## 方法

 一种幼稚的方法是反复搜索`"WUB"`并将其从字符串中删除，直到没有为止。 每次删除都会移动字符串并花费 O(n) 成本，在最坏的情况下可能会出现 O(n) 次，从而导致 O(n²) 行为。 虽然这对于 n ≤ 200 仍然是可以接受的，但它是不必要的间接，并且使连续定界符的边缘处理变得尴尬，特别是在确保在重构​​单词之间正确插入空格时。 

更直接的方法是在处理时从左到右扫描一次字符串`"WUB"`作为单个分隔符模式。 每当我们遇到`"WUB"`，我们完全跳过它。 每当我们遇到不匹配的片段时，我们都会将其收集为单词的一部分。 关键的观察是`"WUB"`其行为类似于分隔符，它永远不会出现在输出中，并且永远不会贡献字符。 这将问题转化为从具有已知固定长度分隔符的流中提取令牌。 

关键的改进是避免构造中间字符串或重复修改输入。 相反，我们只在字符串中移动指针一次，仅在单词之间转换时提取有意义的字符并插入空格。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 重复删除`"WUB"`| O(n²) | O(n) | 已被接受但效率低下|
 | 跳过定界符的线性扫描 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 初始化索引`i = 0`和一个空列表`words`。 该列表将按顺序存储重构的单词。 
2. 虽然`i`小于字符串长度，检查是否从以下位置开始的子串`i`比赛`"WUB"`。 

当匹配时，前进`i`减 3 以完全跳过此分隔符。 

这有效是因为`"WUB"`始终是结构分隔符，而不是真实单词的一部分。 
3.如果`"WUB"`未在该位置找到`i`，开始收集单词。 

创建一个空缓冲区并继续前进`i`而当前位置并未开始`"WUB"`顺序。 

将每个字符附加到缓冲区中。 

这确保我们提取真实字符的最大连续序列。 
4.一旦`"WUB"`遇到或字符串结束，将缓冲区转换为单词并将其附加到`words`如果它非空。 

这可以防止连续分隔符导致的空字。 
5. 处理整个字符串后，使用单个空格连接所有收集的单词并输出结果。 

关键的想法是`"WUB"`充当硬边界。 每次我们跳过它时，我们都保证位于单词之间或边界处，因此任何累积的字符都会形成一个完整的原始单词。 

### 为什么它有效

 正确性取决于在任何时刻我们要么站在一个有效单词的开头，要么站在一个有效单词的开头。`"WUB"`堵塞。 自从`"WUB"`永远不会出现在真实的单词中，跳过它不能删除有意义的数据。 每个字符不属于`"WUB"`块恰好属于一个原始单词，并且字符按顺序附加，保留与原始歌曲中完全相同的单词顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

words = []
i = 0

while i < n:
    if i + 3 <= n and s[i:i+3] == "WUB":
        i += 3
        continue

    buf = []
    while i < n and not (i + 3 <= n and s[i:i+3] == "WUB"):
        buf.append(s[i])
        i += 1

    if buf:
        words.append("".join(buf))

print(" ".join(words))
```执行直接遵循扫描策略。 外循环确保我们一次性处理字符串。 内循环构建一个单词，直到`"WUB"`边界出现。 

一个微妙的点是重复检查`i + 3 <= n`在子字符串比较之前。 这可以避免切片超出字符串末端并保持边界处的逻辑安全。 另一个重要的细节是`buf`在附加之前进行保护，这可以防止连续出现空字`"WUB"`序列。

 ## 边缘情况

 一种重要的边缘情况是当字符串以多个开头时`"WUB"`块，例如`"WUBWUBABC"`。 算法反复跳过`"WUB"`直到达到`'A'`, so no empty word is created at the beginning.

 另一种情况是`"ABCWUBWUBDEF"`，其中单词之间出现多个分隔符。 扫描同时治疗`"WUB"`出现作为分隔符而不生成空缓冲区，产生`"ABC DEF"`。 

最后一个案例是`"WUBWUBWUB"`，其中整个输入由分隔符组成。 缓冲区永远不会被填满，因此不会附加任何单词，并且输出正确地是一个空字符串。
