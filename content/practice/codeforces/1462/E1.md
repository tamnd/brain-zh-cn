 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，其中每个元素都在 1 和`n`，我们被要求计算三元组的数量`(i, j, z)`这样三元组中的最大值与最小值最多相差 2。数组可以包含重复项，并且要求我们有效地处理多个测试用例。 每个测试用例都有自己的数组，所有测试用例的长度总和不超过 200,000。 

该问题需要计算具有有限范围的三个元素的组合。 一个幼稚的实现会明确地考虑每个三元组，这将是`O(n^3)`并且不可行`n`最多 2·10^5。 我们需要一种利用排序或计数来降低复杂性的方法。 非明显的边缘情况包括元素全部相同的数组、数字分散且不存在有效三元组的数组，以及小于三个元素且答案必须为零的数组。 

## 方法

 蛮力方法是迭代所有可能的三元组`(i, j, z)`具有三个嵌套循环，检查是否`max - min ≤ 2`。 这是正确的，但太慢，而且复杂`O(n^3)`。 

关键的见解是对数组进行排序。 排序后，任何有效的三元组必须由排序数组中的连续元素组成，因为包含相距较远的元素将超过最大差异。 使用两个指针，我们可以迭代数组：修复起始索引`l`并扩展结束索引`r`尽可能地使得`a[r] - a[l] ≤ 2`。 然后，有效三元组的数量`a[l]`因为最小的元素是从其中选择 2 个附加元素的方法数`r - l`剩余元素。 这是使用组合计算`C(n, 2)`。 

对数组成本进行排序`O(n log n)`，以及两指针扫描成本`O(n)`，给出总体`O(n log n)`每个测试用例。 考虑到限制，该方法是有效的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 太慢了|
 | 排序+两个指针| O(n log n) | O(n log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，请阅读`n`和数组`a`。 
3. 排序`a`按非递减顺序。 排序可确保任何有效三元组中的元素是连续的。 
4. 初始化指针`l = 0`标记候选段和变量的开始`ans = 0`累积有效三元组的总数。 
5. 迭代`r`在数组索引上。 尽管`a[r] - a[l] > 2`, 增量`l`缩小段直到满足差异约束。 
6. 对于每个位置`r`，计算段中的元素数量：`length = r - l`。 如果`length ≥ 2`，使用计算三元组的数量`length * (length - 1) // 2`并添加到`ans`。 
7.全部处理完毕后`r`， 打印`ans`。 

工作原理：排序保证任何差值超过 2 的三元组不能包含有效段之外的元素。 两指针方法确保所有可能的有效段都被计数一次。 组合公式正确地计算了每个段的三元组数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()
        ans = 0
        l = 0
        for r in range(n):
            while a[r] - a[l] > 2:
                l += 1
            length = r - l
            if length >= 2:
                ans += length * (length - 1) // 2
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先对数组进行排序，使连续元素成为三元组的唯一候选元素。 左指针`l`仅当差值超过 2 时才前进，确保我们永远不会包含无效元素。 组合公式计算所有以位置结束的有效三元组`r`有效地避免嵌套循环。 边界条件，例如短于 3 个元素的线段，可以自然处理，因为`length < 2`导致零添加。

 ## 边缘情况

 对于元素少于 3 个的数组，`r-l`永远不会达到 2，因此答案自动为 0。对于所有元素相等的数组，段会增长到整个数组长度，并且组合计数可确保包含所有三元组。 对于没有有效三元组的数组，指针`l`移动以防止任何无效差异，从而产生零计数。 每个场景都可以通过两指针和组合方法自然地处理。
