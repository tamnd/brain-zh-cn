 ## 解决方案
 ## 问题理解

 波利卡普有一个最喜欢的整数序列，但我们没有直接看到它。 相反，我们看到的是他执行特殊写作过程的结果。 他将第一个元素写在白板的左端，将第二个元素写在右端，然后交替将下一个可用元素放置在尽可能远的左侧，然后尽可能远的右侧，继续这种锯齿形，直到写入整个序列。 我们的任务是从最终的白板状态重建原始序列。 

输入给出了测试用例的数量，以及每个测试用例的白板序列的长度和序列本身。 我们必须为每个测试用例输出 Polycarp 最喜欢的原始序列。 

鉴于$n$最多可以有 300 个，并且可以有最多 300 个测试用例，一个解决方案的运行时间大约为$O(n)$每个测试用例是可以接受的。 不存在任何需要更快速度的限制，甚至$O(n^2)$方法可能会通过，因为$300^2 \cdot 300$略低于 3000 万次操作，但我们可以做得更好。 

当序列只有一个元素、所有元素都相同或者最大或最小元素出现在末尾时，就会出现边缘情况。 例如，如果白板顺序是`[42]`，输出必须简单地是`[42]`。 如果所有元素都相等，例如`[1, 1, 1, 1]`，输出是相同的序列。 在这些情况下，假设严格增加或减少模式的粗心实现可能会失败。 

## 方法

 暴力方法会尝试反向模拟波利卡普的写作过程。 人们可以尝试左右插入的所有可能组合来重建原始序列，但这很快就变得不可行，因为$n$由于排列的阶乘数而增长。 

关键的观察是，波利卡普总是将最大的剩余数字写在白板的极端之一。 换句话说，白板序列的第一个元素是原始序列的第一个元素。 之后，我们可以维护两个指针，一个在白板序列的开头，一个在结尾，并按照重建锯齿形放置的顺序从任一端选取元素。 通过迭代地选择两个极端中尚未使用的较大者，我们可以在一次传递中重建原始序列。 

观察结果将问题简化为两指针遍历：始终从白板序列中选择两个可用极值中较大的一个，将其附加到重建序列中，并将其从考虑中删除。 这是可行的，因为 Polycarp 总是将下一个最大的未放置数字放置在极值处，并且放置顺序从左到右交替，但按最大值选择可确保可以贪婪地重建正确的顺序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 两指针贪婪 | 每个测试用例 O(n) | O(n) | 已接受 |

 ## 算法演练

 1.初始化一个空列表`a`保存重建的最喜欢的序列。 
2.使用两个指针，`l`在白板序列的开始处`b`和`r`在最后。 
3. Repeat while`l <= r`:

 1. 比较`b[l]`和`b[r]`。 
2. 将两者中较大的一个添加到序列中`a`。 
3.如果`b[l]`较大，增量`l`。 否则，递减`r`。 
4.处理完所有元素后，输出`a`作为重建的序列。 

这样做的原因是白板序列中剩余的最大元素必须对应于 Polycarp 放置在白板两端的下一个元素。 通过始终选择两个可用极值中的最大值，我们尊重交替放置顺序并正确重建原始序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))
        a = []
        l, r = 0, n - 1
        while l <= r:
            if b[l] > b[r]:
                a.append(b[l])
                l += 1
            else:
                a.append(b[r])
                r -= 1
        print(' '.join(map(str, a)))

if __name__ == "__main__":
    solve()
```此代码读取测试用例的数量，然后为每个测试用例读取白板序列。 两指针方法确保我们始终选择正确的元素来重建原始序列。 我们仔细处理指针以避免差一错误并确保包含所有元素。 每个测试用例的打印都在最后完成。
