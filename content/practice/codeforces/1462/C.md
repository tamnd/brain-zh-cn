 ## 解决方案
 ## 问题理解

 给定一个目标数字和，我们必须构造最小的正整数，其数字全部不同并且其数字之和恰好等于该目标。 

输出不仅仅是任何有效数字，而是标准十进制排序中的最小数字。 这意味着我们正在有效地选择一组不同的数字，决定它们的排列，并从中形成字典顺序上可能的最小数字。 

关键限制是数字必须是唯一的。 由于数字范围仅从 0 到 9，因此我们永远不能使用超过 10 个不同的数字，更重要的是，使用不同数字可实现的最大总和是固定的。 最大可能的集合是 0 到 9 的所有数字，其总和为 45。任何大于 45 的输入都立即不可能。 

这会创建一个非常紧张的搜索空间：最多 10 位数字，且总和有限。 

零的存在会产生微妙的边缘情况。 零对总和没有任何贡献，但会影响排序。 例如，允许使用数字 0，但它不能作为最终数字中的前导数字出现。 在没有正确处理前导零的情况下对所选数字进行排序的简单方法可能会意外地产生无效的最小表示。 

另一个边缘情况是像 1 或 2 这样的小金额，其中贪婪选择的行为根据排序策略而有所不同。 例如，如果我们试图在满足总和约束的同时最小化字典顺序值，那么从最小向上选择数字并不是最佳选择。 

## 方法

 一个强力的想法是尝试从 1 到 9（以及可选的 0）的所有数字子集，检查它们的总和，然后生成所有排列以找到最小的有效数字。 原则上这是正确的，因为搜索空间是有限的：最多有$2^{10} = 1024$子集，最多 10 个！ 每个子集的排列。 然而，在最坏的情况下，这仍然会导致数百万个候选数，考虑到问题的结构，这是不必要的。 

关键的观察是我们想要一个不同数字的子集，其总和恰好是$x$，并且我们希望结果数字尽可能小。 为了最小化结果数字，我们希望较小的数字尽早出现。 然而，较小的数字也会更慢地减少总和，这与我们需要有效地达到固定目标总和时所希望的相反。 

这就产生了一种经典的贪婪张力：为了在使用不同数字的同时快速求和，我们应该首先选择大数字。 但为了最小化最终的数量，我们应该稍后按升序排列它们。 

所以正确的策略是从 9 到 1 贪婪地选择数字，如果不超过剩余的总和，总是取一位数字。 这确保我们使用尽可能少的数字，并尽早优先考虑较大的贡献。 选择集合后，我们按升序对其进行排序以构造尽可能小的数字。 

数字 0 对于总和本身没有用处，但如果需要，可以将其包含在内，并且始终按排序顺序放置在所有非零数字之后，这自然会阻止它成为前导数字，除非它是唯一的数字。

 | --- | --- | --- | --- |
 | 蛮力子集和排列 | O(10!·2^10) | O(10!·2^10) | O(1) | O(1) | 太慢了 |

 ## 算法演练

 1. 检查目标总和是否达到$x$大于 45。如果是，则立即输出 -1，因为即使使用所有数字 0 到 9 也无法达到该总和。 这可以在任何施工之前消除不可能的情况。 
2. 初始化一个空列表来存储选定的数字并设置一个变量`rem = x`代表我们仍需要达到的剩余金额。 
3. 将数字从 9 向下迭代到 1。在每个数字处`d`，检查是否`d <= rem`。 如果是，请包括`d`在答案集中并减去`d`从`rem`。 我们在这里跳过 0，因为它无助于减少剩余的总和。 
4. 循环结束后，如果`rem`不为零，输出-1。 这意味着我们无法使用 1 到 9 之间的不同数字来精确表示总和。 
5. 否则，按升序对选定的数字进行排序，并将它们连接起来形成最终的数字。 排序是必要的，因为我们想要尽可能小的整数，并且将较小的数字放在前面总是会减少数值。 

### 为什么它有效

 从 9 往下的贪婪选择确保我们使用尽可能少的数字，因为数字越大，就越积极地减少剩余的总和。 因为我们从不重复使用数字，所以该构造相当于选择 {1..9} 的子集，其总和恰好为 x。 在所有这些子集中，任何有效的解决方案仅在数字顺序上有所不同，并且对这些数字进行逐渐排序总是会产生尽可能小的整数。 因此，该算法将问题分为子集选择（可行性的贪婪最优）和排序（排序的最小表示），保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve(x):
    if x > 45:
        return "-1"
    
    rem = x
    chosen = []
    
    for d in range(9, 0, -1):
        if d <= rem:
            chosen.append(d)
            rem -= d
    
    if rem != 0:
        return "-1"
    
    chosen.sort()
    return "".join(map(str, chosen))

t = int(input())
out = []
for _ in range(t):
    x = int(input())
    out.append(solve(x))

print("\n".join(out))
```实现直接遵循贪心构造。 可行性检查`x > 45`避免不必要的工作。 从 9 到 1 的后向循环确保我们优先考虑大数字，从而最大限度地减少所选元素的数量。 最后的排序至关重要，因为单独的贪婪选择并不能保证最小的数字顺序。 

一个常见的实现错误是在选择之前对数字进行排序或从 1 向上迭代，这往往会产生许多小数字，并且即使存在解决方案也可能无法达到总和。

 ## 边缘情况

 一个重要的边缘情况是当总和等于 45 时。该算法将数字 9 向下选择为 1，将所有可用数字恰好消耗一次。 排序产生 123456789，这是所有数字的最小可能排列。 

另一个边缘情况是当总和略高于可达子集边界时，例如 8 或 10。对于 x = 10，贪婪过程会跳过 9 和 8，选择 7（太大而无法容纳），然后最终选择 9？ 实际上它不能，所以它选择9被跳过，8被跳过，7被跳过，6被跳过，5被跳过，4被跳过，3被跳过，2被跳过，然后1和9无法完成，所以它选择9？ 不，它不适合。 最终选择变成[9? invalid]，rem 保持非零，因此输出为 -1。 这表明贪婪选择不仅仅是选择直到耗尽；而是选择。 可行性必须通过剩余金额来验证。 

最后一个微妙的情况是 x = 1。算法直接选择数字 1 并产生一位数的输出。 任何包含 0 的尝试都是有害的，因为它无法帮助满足总和，并且如果处理不当可能会错误地影响排序。
