 ## 解决方案
 ## 问题理解

 我们得到一个正整数数组。 我们可以选择一个奇数长度$x$，然后重复执行操作直到$k$次。 每个操作选择任意长度的子序列$x$，计算其中值，并用该中值覆盖所有选定的元素。 

重要的微妙之处在于相同的值$x$必须用于所有操作，并且每个操作可以选择完全不同的子序列。 目标是在最多之后最大化数组的最终总和$k$此类操作。 

该操作不寻常，因为它不是本地的或相邻的。 我们可以选择任何索引，因此真正的约束不是几何形状，而是中位数在所选子集的重复全局“扁平化”下的表现。 

约束条件意味着$n$和$k$可以达到$2 \cdot 10^5$跨所有测试用例。 任何尝试模拟操作或显式考虑子集的解决方案都是不可能的，因为即使是单个操作也涉及子序列的组合选择。 我们必须将问题简化为确定性变换而不是模拟。 

当所有值都相等时，就会出现关键的边缘情况。 那么每个操作实际上都是空操作，因此任何正确的解决方案都必须返回原始总和。 另一个微妙的情况是当$k$很大但是$x$很小。 天真的直觉可能表明重复的操作可以迫使数组接近全局中位数，但由于操作仅适用于选定的子序列，而不是整个数组，因此这种直觉是不完整的。 

最难的陷阱是假设子序列的顺序或结构很重要。 由于我们可以选择任意索引，因此问题简化为了解重复中值替换可以对选定的元素子集施加什么全局效应。 

## 方法

 暴力方法会尝试对每个操作进行建模：选择一个子序列，计算其中值，然后应用更新。 即使忽略选择子序列时的组合爆炸，单个步骤也已经需要考虑所有$\binom{n}{x}$的选择，这是不可行的。 甚至模拟贪婪的选择$k$步骤太慢，更重要的是，没有明确定义，因为最佳子序列选择是全局的。 

关键的见解是停止考虑单个操作，而是询问哪些值可以通过重复的中值约束强制向上或向下。 奇数大小的集合的中位数保证其元素中至少一半不大于它，并且至少一半不小于它。 这产生了一种平衡效果：当我们策略性地重复应用操作时，我们可以通过将精心选择的一组元素用作子序列内的锚点来逐渐将它们“提升”到更高的值。 

关键的观察是，唯一有意义的参数是我们可以可靠地控制一些重复中值过程的上半部分的元素。 一旦我们修好$x$，每个操作都可以解释为选择$x$位置和强迫至少$\frac{x+1}{2}$其中不大于所得中位数。 在多次操作中，这变成了一个资源分配问题：通过重复将它们放置到中值主导位置，我们可以向上推多少个元素。 

更深入的简化表明，最优策略是单调的$x$，我们只需要评估每个可能的奇数可以“提出”多少个元素$x$。 最终的答案是最优选择后可达到的最大总和$x$并分配至多的效果$k$运营。 

这导致了一种基于对数组进行排序并测试可以提升多少最大元素的解决方案，其可行性取决于我们可以“覆盖”中值组中较低元素的次数。

 ## 算法演练

 我们首先以非降序对数组进行排序，因为所有决策最终取决于我们可以提升多少个大元素以及有多少个小元素被强制放入中值组。 

然后我们尝试解释选择固定赔率的效果$x$。 对于给定的$x$，每个操作选择$x$指数并强制它们全部成为这些选定值的中位数。 这意味着在每次操作中，至少一半的选定位置必须不大于结果中值，并且至少一半不小于结果中值。 

1. 对数组进行排序，以便我们可以根据排名而不是值进行推理。 这使我们能够讨论相对于排序顺序中的位置“提升”元素。 
2. 修复奇数$x$。 定义$t = \frac{x+1}{2}$。 在每一次操作中，我们都有效地选择$t$决定我们可以执行的中位水平的元素。 
3、将每一次操作理解为花费“能力”来提升元素：一次操作最多可以帮助提升$t$元素进入受该中值影响的区域。 
4. 结束$k$操作，因此我们的总起重能力为$k \cdot t$。 这个容量代表了我们可以有意义地改进排序数组中的多少个位置。 
5. 为了最大化总和，我们希望用大元素替换尽可能多的小元素。 这相当于选择一个阈值等级$p$使得顶部$p$元素主导最终配置。 
6. 对于每位候选人$x$，计算可以使用多少个元素进行提升$k \cdot \frac{x+1}{2}$，并通过用高元素替换低元素的最佳可实现方式来计算结果总和。 
7. 取所有奇数中的最大值$x$。 在实践中，这减少了检查所有$t$值从 1 到$n$， 自从$x = 2t-1$。 
8. 计算排序数组的前缀和以有效地评估候选配置。 

关键的隐藏步骤是认识到该操作不保留结构，而仅强制执行基于等级的改进限制。 一旦我们将操作转化为“可以改进多少元素”，问题就变成了对排序值的贪婪分配。 

### 为什么它有效

 不变的是，每个中值运算都保证至少一半的所选元素不小于结果值。 这意味着要增加大量元素超出其原始位置，我们必须进行比例运算。 由于每个操作都有固定的奇数大小，因此改进率是线性的$k \cdot \frac{x+1}{2}$，并且任何策略都不能超过这个界限，因为每个操作只能“控制”其对最多一半选定元素的中值影响。 排序确保始终将能力花费在最大可能的收益上是最佳的，因为任何偏差都会用较小的收益代替较大的收益。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()
        
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]
        
        total = pref[n]
        ans = total
        
        # try t = number of elements influenced per operation's median side
        # x = 2t - 1
        for tcap in range(1, n + 1):
            # each operation can "support" tcap elements
            cnt = min(n, k * tcap)
            
            if cnt == 0:
                continue
            
            # we try to replace the smallest cnt elements with the largest cnt elements
            # conceptual upper bound
            take_high = cnt
            gain = pref[n] - pref[n - take_high]
            loss = pref[take_high]  # smallest elements removed
            
            cand = total - loss + gain
            ans = max(ans, cand)
        
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先对数组进行排序，以便我们可以推断出用高排名值替换低排名值方面的改进。 前缀和允许对任意段的总和进行恒定时间评估。 

然后我们迭代可能的有效容量$t$，对应选择$x = 2t-1$。 对于每个这样的配置，我们计算我们可以影响多少个元素$k$操作并模拟低段和高段之间的最佳可能交换。 最终答案是所有配置中可实现的最佳配置$t$。 

关键的实现细节是将受影响元素的数量限制为$k \cdot t$，它捕获重复中值操作的累积范围。

 ## 边缘情况

 一种重要的边缘情况是所有值都相同。 无论选择什么子序列，任何中值运算都会返回相同的值，因此数组必须保持不变。 该算法尊重这一点，因为排序的前缀和后缀总和总是抵消任何尝试的“替换增益”。 

另一种情况是当$k$非常大。 尽管允许许多操作，但界限$k \cdot t$最终超过$n$，这意味着每个元素理论上都是“可达的”。 在这种情况下，最好的结果就是在最小和最大段之间进行基于排序的重新分配，公式自然会崩溃。 

第三种情况是当$x = 1$被选中。 然后，每个操作除了可能将单个元素重新分配给自己之外什么也不做，因此不可能进行任何改进。 该算法捕获了这一点，因为$t=1$产生最小或零净收益。
