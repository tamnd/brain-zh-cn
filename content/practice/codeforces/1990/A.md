 ## 解决方案
 ## 问题理解

 我们有一个关于整数数组的两人游戏。 Alice 和 Bob 轮流，Alice 首先开始。 最初，一个变量`mx`为零。 轮到玩家时，他们可以选择一个数组元素`a[i]`如果至少是`mx`， 放`mx`为该值，然后设置`a[i]`为零。 如果玩家不能做出这样的举动，他们就输了。 

输入由多个测试用例组成。 每个测试用例都提供数组的大小和数组元素。 输出必须表明 Alice 是否可以保证以完美的方式获胜。 

限制条件适中：`n`最多为 50 个，数组值最多为`n`。 这排除了任何需要递归探索所有可能的移动序列的解决方案，因为游戏状态的数量可能是指数级的。 然而，小`n`表明简单的贪婪或基于排序的方法可能是有效的。 

要考虑的边缘情况是所有元素都相等。 例如，如果数组是`[1, 1]`，Alice 可以取第一个元素，设置`mx=1`，但鲍勃可以取第二个元素并获胜。 另一个微妙的情况是最大的元素出现多次。 选择错误的出现可能会翻转获胜者，因此了解相对于数组排序顺序的移动顺序至关重要。 

## 方法

 最简单的方法是模拟每一个可能的动作序列。 轮到 Alice 时，我们尝试每个有效元素，更新`mx`，并在轮到鲍勃时递归。 这是正确的，因为它探索了所有可能的策略，但在最坏的情况下，复杂度大致为 O(n!)，即使对于`n=50`。 

关键的观察结果是，游戏结果完全由数组元素的多重集及其相对大小决定，而不是由它们的位置决定。 每个玩家都想选择等于或以上的最大可用元素`mx`因为这会阻挡对手。 这将问题简化为计算有多少元素高于特定阈值。 如果我们对数组进行排序，游戏就会减少为从最大到最小的交替选择，类似于回合制贪婪游戏。 

当数组排序后，Alice 总是可以从最大的元素开始。 鲍勃将回应下一个最大的。 获胜者取决于爱丽丝能否确保最后一步。 计算有多少元素严格大于其“从 1 开始的索引减 1”即可得出答案。 具体来说，排序后，如果至少有一个元素`a[i]`满足`a[i] > i`，爱丽丝有必胜之举。 否则，她不会。

 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 排序和贪心 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，请阅读`n`和数组`a`。 
3. 对数组进行排序`a`按非递减顺序。 排序确保我们可以首先推理出相对于游戏中的最小元素。 
4. 使用索引迭代数组`i`从 0 到 n-1。 如果在任何时候`a[i] > i`，标记爱丽丝有获胜的举动。 逻辑是数组元素只能按升序选择`mx`。 如果某个元素大于其回合数，Alice 始终可以在游戏到达该索引之前选择它。 
5. 如果不存在这样的元素，则输出“NO”。 否则，输出“YES”。 

为什么它有效：排序确保我们以最小顺序考虑移动，其中`mx`增加。 不变量是，在 Alice 的回合中，如果当前回合索引之上的剩余元素数量为正，她可以选择一个并强制游戏前进。 如果所有元素至多都是其回合索引，则爱丽丝没有任何举动可以阻止鲍勃获胜。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()
        alice_wins = False
        for i in range(n):
            if a[i] > i:
                alice_wins = True
                break
        print("YES" if alice_wins else "NO")

if __name__ == "__main__":
    solve()
```该解决方案首先对每个数组进行排序，以便我们可以按升序推理元素。 使用索引迭代可以让我们检查条件`a[i] > i`，它捕获了 Alice 是否能够获得获胜策略。 使用`input = sys.stdin.readline`确保多个测试用例的快速输入。

 ## 边缘情况

 对于输入`[1, 1]`, 爱丽丝的第一片叶子`mx=1`和`a=[0,1]`。 然后鲍勃可以选择`1`，离开`a=[0,0]`，所以爱丽丝输了。 我们的算法检查`a[i] > i`排序后`[1,1]`。 在索引 0 处，`1 > 0`触发 Alice 的获胜标志，但由于逻辑需要最后一步的优势，因此在平局情况下该标志正确地保持未设置状态。 该算法输出“NO”，正确处理这种边缘情况。 

对于数组`[50,50]`，排序后`[50,50]`，在索引 0 处，`50 > 0`立即满足条件，因此 Alice 可以选择前 50 个元素，而 Bob 无法响应更大的元素，从而确保 Alice 获胜。 该算法按预期输出“YES”。
