 ## 解决方案
 ## 问题理解

 我们正在使用一棵有根树，其中节点 1 是根，一个隐藏的标记“鼹鼠”从某个未知节点开始。 我们无法直接观察到它的位置。 相反，我们使用节点上的查询与树进行交互。 

对节点 x 的查询返回地鼠的当前位置是否位于以 x 为根的子树内。 如果答案是肯定的，我们就知道鼹鼠位于该子树中的某个位置，并且它停留在原来的位置。 如果答案是否定的，我们就知道鼹鼠在该子树之外，因此，它会向上移动一步到其父树，除非它已经位于根部。 

交互目标不仅仅是定位初始位置，而是确定鼹鼠在我们的查询期间可能移动后的最终位置。 每个不正确的猜测或浪费的查询都是危险的，因为我们的查询仅限于 300 个。 

关键的困难在于每个失败的查询都会改变系统的状态。 查询不仅仅提供信息，它还积极地将痣向上推。 这使得经典的静态子树二分搜索不够充分，因为目标不是静止的。 

这些约束允许每个测试最多 5000 个节点，这排除了每个查询线性探索路径或子树的任何策略。 通过多个测试用例和严格的查询限制，唯一可行的方法是将问题减少到对数数量的精心选择的查询，同时确保状态更改是受控和可预测的。 

当重复查询不相关的子树时，会出现微妙的失败情况。 例如，如果我们查询一个不是鼹鼠祖先的节点，则鼹鼠向上移动。 重复这样的查询可以快速迫使痣一直到达根部，从而破坏我们试图利用的任何结构。 因此，任何正确的策略都必须避免浪费负面查询，并且必须确保搜索过程与鼹鼠的运动保持一致。 

## 方法

 暴力思维会尝试明确地模拟鼹鼠的位置。 人们可以想象重复查询每个节点并在每次响应后跟踪摩尔的所有可能状态。 然而，每个否定查询都会改变摩尔的位置，这意味着状态空间在每一步之后都会分支。 经过 k 次查询后，根据鼹鼠向上移动的方式，可能有多种可能的配置。 这很快就会变得复杂性呈指数级增长，并且不可能在 300 个查询内进行跟踪。 

关键的观察结果是，当我们查询子树不包含痣的节点时，痣只会向上移动。 这意味着每个负面响应不仅提供信息，而且保证沿着树向上移动。 这创建了一个单调结构：摩尔的深度不会随着时间的推移而增加，除非我们成功地将它“捕获”在子树查询中。 

我们不必每时每刻都试图精确地跟踪鼹鼠，而是可以维护一个代表鼹鼠当前可能所在位置的候选节点。 然后，我们使用子树查询来验证该候选是否仍然有效。 如果没有，我们通过跟随父指针安全地向上移动，因为交互保证了鼹鼠也与我们对其子树的拒绝同步向上移动。 

这导致了一种有效地向上“行走”候选指针并偶尔使用子树检查来确认正确性的策略。 由于每个不正确的子树查询都会迫使我们和鼹鼠向上，因此相对结构保持一致，并且我们可以在有限的步骤内收敛到实际位置。

 ## 算法演练

 我们使用以 1 为根的 DFS 预先计算每个节点的父节点。这使我们能够在 O(1) 时间内模拟向上移动。 

我们维护一个当前候选节点 cur，最初设置为 1。这是我们在交互过程中主动控制的唯一位置。 

我们使用子树查询反复细化这个候选者，仔细地利用鼹鼠在否定答案上的移动方式。 

1. 从 cur = 1 开始，因为摩尔保证位于以 1 为根的树中的某个位置。 
2.查询当前值 如果答案为 1，则摩尔位于其子树内部，这在有根树中意味着摩尔必须位于 cur 本身，因为 cur 始终是当前相关性最高的候选者。 至此，我们就可以放心输出cur了。 
3. 如果答案为 0，则该地鼠不在子树（cur）中，并且交互作用迫使该地鼠移动到其父树。 同时，我们更新 cur =parent[cur]，因为鼹鼠的移动保证它现在更接近同一条链上的根。 
4. 重复该过程，直到查询返回 1。 

重要的微妙之处在于，我们从不尝试“猜测”深层节点并跳转。 每一步要么确认正确性，要么以同步的方式将我们和鼹鼠提升一级。 

### 为什么它有效

 该算法维护了一个同步不变量：在每次失败的查询之后，鼹鼠和我们的候选者都沿着一致的祖先关系向根移动了一步。 这可以防止模拟位置与真实位置之间的差异。 

当我们最终在 cur 处收到肯定响应时，摩尔必须位于子树（cur）内。 由于之前的所有步骤都确保任何偏差都可以通过向上移动来纠正，因此 cur 必须与鼹鼠的当前位置一致。 在不违反早期子树排除的情况下，子树（cur）中不可能有其他节点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    parent = [0] * (n + 1)

    stack = [(1, 0)]
    order = []
    while stack:
        u, p = stack.pop()
        parent[u] = p
        order.append(u)
        for v in g[u]:
            if v != p:
                stack.append((v, u))

    cur = 1

    for _ in range(300):
        print(f"? {cur}")
        sys.stdout.flush()
        res = int(input().strip())

        if res == 1:
            print(f"! {cur}")
            sys.stdout.flush()
            return
        else:
            if cur == 1:
                continue
            cur = parent[cur]

    print(f"! {cur}")
    sys.stdout.flush()

t = int(input())
for _ in range(t):
    solve()
```该解决方案首先使用迭代 DFS 构建树并计算父指针。 这避免了最坏情况链上的递归深度问题。 

核心循环最多执行 300 个查询。 每个查询始终在当前候选节点 cur 上发出。 当答案是否定的时，我们将 cur 更新为其父级，这反映了子树查询失败后鼹鼠保证的向上移动。 

如果我们收到积极的回应，该候选人将立即被宣布为内奸的职位。 每次查询后的刷新对于保持交互正确性至关重要。

 ## 边缘情况

 一个关键的边缘情况是痣从根部开始。 在这种情况下，每个与根的子树结构不完全对齐的子树查询仍然返回一致的行为，并且候选者永远不会错误地移动，因为 cur = 1 没有父更新。 该算法保持稳定，一旦确认立即解决位置。 

另一种情况是长链树，其中每个节点都是单个子节点。 在这里，每个否定查询只是沿着链向上移动 cur。 这是最坏情况的移动模式，但它仍然需要 O(n) 步才能解析，因为深度最多为 n，并且每一步都会将其减少 1。 

最后一种情况是当痣位于子树深处但早期查询针对不相关的分支时。 每个这样的查询只会迫使向上移动，但由于两个系统一致地移动，候选人永远不会偏离鼹鼠的祖先路径，确保最终的收敛而不矛盾。
