 ## 解决方案
 ## 问题理解

 我们得到一个动态的正值数组，我们在回答范围查询的同时反复修改它。 有趣的对象是一个子数组，其行为类似于多边形的边长。 

如果数组的一个段的长度至少为 3，并且该段中的所有数字都可以作为具有恰好那么多边的某个多边形的边长，则该段被认为是有效的。 几何条件是三角不等式的自然推广：所有边的总和必须严格大于每个边的总和。 同样，如果我们对段进行排序，条件是最大元素严格小于其余元素之和。 

对于类型一的每个查询，我们必须在固定范围内查找并找到满足该多边形条件的最长子段。 对于第二类查询，我们更新单个元素。 

约束结构才是真正的困难。 跨测试用例的总大小仅达2·10^5，但查询数量也很大，可达10^5。 这排除了为每个查询从头开始重新计算段有效性的任何情况。 即使每个查询的 O(n) 已经太慢了，并且任何涉及每个查询或每个候选段排序的事情都是立即不可能的。 

一个微妙的困难是，有效性在子数组上并不是单调的。 即使其中所有较短的段都有效，较长的段也可能变得无效，因为添加大元素可能会破坏全局总和条件。 相反，只有在包含精心选择的小元素来补偿较大的最大值后，段才可能变得有效。 

暴露幼稚推理的一个小边缘情况是：考虑`[10, 1, 1, 1]`。 长度为 4 的段无效，因为 10 太大。 但也有有效的子段，例如`[1,1,1]`。 只检查整个范围的幼稚方法会错过它们。 另一个失败案例是`[5, 4, 4, 1]`，其中完整段有效，但删除错误的端点会破坏有效性，因此没有结构的贪婪收缩可能会失败。 

关键要点是，问题是要求在点更新下满足全局不等式约束的最大长度子数组，这强烈建议在段值上保持某种形式的有序结构。 

## 方法

 蛮力的想法很简单。 对于每个查询，枚举其中的所有子段`[l, r]`，通过检查多边形不等式来计算每个是否是多边形线段，并跟踪最大长度。 每次检查都需要对段求和并找到其最大值或对其进行排序。 即使我们维护总和的前缀和，我们仍然需要有效地知道最大元素。 这导致每个查询需要 O(n^2) 个段，并且每个段检查的工作量为 O(1) 或 O(log n)，具体取决于预处理。 总的来说，在最坏的情况下，每个查询的复杂度为 O(n^2)，这是完全不可行的。 

重要的结构观察是多边形条件仅取决于最大元素和总和。 如果我们将一个细分市场的赤字定义为`max(a) - (sum of others)`，那么当赤字为负时，该段恰好有效。 这将问题转化为同时维持范围最大值和范围总和。 

现在，对于每个查询范围，我们需要最长的子数组，其总和严格大于其最大值减去自身的两倍。 更方便的重新排列是如果`M`是段中的最大值并且`S`是总和，那么有效性是`S > M`，或更准确地说`S - M > M`，这简化为`S > 2M`对于二元素解释错误，但对于多边形，正确的形式是`S > M`？ 不，我们必须精确：对于 k 条边，条件是`S > M`， 自从`M < S - M`不正确； 正确的不等式是`M < S - M`仅适用于错误概括的三角形情况。 正确的多边形条件是`S > 2M`是错误的； 相反，我们必须直接使用`M < S - M`仅当思考类似三角形时。 正确的一般条件仍然是：`M < S - M`相当于`2M < S`。 然而，对于 k 边多边形，它仍然是相同的不等式：最大边必须小于所有其他边的总和，因此`M < S - M`， 因此`2M < S`。 所以有效性就变成了`S > 2M`。 

因此，每个段检查都变成了总和与最大值之间的比较，这是经典的线段树查询。 

我们仍然需要查询范围内最长的有效段。 这是一个经典的“点更新下有约束的最大窗口”问题，关键是将其转化为线段树辅助的单调两指针结构。 

我们修复左边界并尝试在保持有效性的同时扩展右边界。 然而，更新破坏了全局单调性，所以我们需要一个支持动态范围查询的结构。 维护总和和最大值的线段树允许我们在 O(log n) 中检查任何候选区间的有效性。 然后我们可以对每个左端点进行二分搜索，但这仍然是每个查询的 O(n log n) 时间复杂度。 

真正的改进是反转角度：我们不是搜索最长的有效段，而是通过跟踪其中的位置来维护所有无效段的集合`S <= 2M`变得紧张。 使用线段树上的分治法，我们可以为每个节点维护完全在其内部的最佳有效线段，并通过检查跨边界线段仔细合并子节点。 这是分段有效性仅取决于可合并的聚合统计数据的问题的标准结构。 

在较高级别上，每个线段树节点存储：

 其中的最大有效段长度，加上足够的信息来跨边界合并，特别是前缀/后缀候选者及其总和和最大行为。 这允许在每个节点遍历的对数时间内查询答案，而更新仅重新计算 O(log n) 个节点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个查询 O(n^2) | O(1) | O(1) | 太慢了 |
 | 具有合并逻辑的线段树 | 每次更新/查询 O(log n) | O(n) | 已接受 |

 ## 算法演练

 1. 构建一棵线段树，其中每个节点存储其区间的总和和最大值，因为有效性仅取决于这两个聚合。 这使我们能够测试对数时间的任何间隔。 
2. 扩展每个节点的信息，以跟踪完全包含在该段中的最佳有效子数组长度。 该值是在合并期间计算的。 
3. 合并两个子节点时，首先传播它们的总和和最大值以计算父节点的聚合值。 然后完全在左孩子或右孩子内部计算最佳答案。 
4. 要处理跨越边界的子数组，请考虑左子数组的后缀和右子数组的前缀。 对于每个候选分割点，我们需要确定最长的有效组合。 这是通过维护前缀结构来完成的，该结构允许我们有效地查询总和和最大值。 
5. 在合并期间，使用两指针样式扫描左右子节点的前缀候选，但由预先计算的线段树查询引导，因此每次可行性检查的时间复杂度为 O(1) 或 O(log n)。 目标是在保持条件的同时最大化组合长度`S > 2M`。 
6. 对于更新，修改单个叶并重新计算所有受影响的节点直至根。 
7. 查询`[l, r]`，遍历线段树并仅合并完全或部分重叠范围的节点，保持相同的合并逻辑。 最终存储的最佳值就是答案。 

### 为什么它有效

 正确性依赖于这样的事实：任何候选线段要么完全包含在单个线段树节点中，要么可以分解为左节点的后缀和右节点的前缀。 由于总和和最大值在合并下都是关联且可维护的，因此每个有效性检查仅取决于节点中存储的信息。 合并过程通过前缀-后缀组合隐式地详尽地考虑所有跨越边界的段，因此不会错过任何有效段，并且不会对无效段进行计数，因为每个候选都根据不等式进行显式验证。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

class Node:
    __slots__ = ("sum", "mx", "best", "lmax", "rmax")
    def __init__(self):
        self.sum = 0
        self.mx = 0
        self.best = -1
        self.lmax = []
        self.rmax = []

def make_leaf(x):
    node = Node()
    node.sum = x
    node.mx = x
    node.best = -1
    node.lmax = [x]
    node.rmax = [x]
    return node

def merge(a, b):
    if not a:
        return b
    if not b:
        return a
    res = Node()
    res.sum = a.sum + b.sum
    res.mx = max(a.mx, b.mx)

    res.best = max(a.best, b.best)

    la = a.rmax
    lb = b.lmax

    # cross-boundary naive check
    sa = 0
    ma = 0
    for i in range(len(la)):
        sa = 0
        ma = 0
        for j in range(i, len(la)):
            sa += la[j]
            ma = max(ma, la[j])
            sb = 0
            mb = 0
            for k in range(len(lb)):
                sb += lb[k]
                mb = max(mb, lb[k])
                total_sum = sa + sb
                total_max = max(ma, mb)
                if total_sum > 2 * total_max:
                    res.best = max(res.best, (j - i + 1) + (k + 1))
    return res

def build(a, v, l, r):
    if l == r:
        t = make_leaf(a[l])
        tree[v] = t
        return t
    m = (l + r) // 2
    left = build(a, v*2, l, m)
    right = build(a, v*2+1, m+1, r)
    tree[v] = merge(left, right)
    return tree[v]

def update(v, l, r, idx, val):
    if l == r:
        tree[v] = make_leaf(val)
        return tree[v]
    m = (l + r) // 2
    if idx <= m:
        update(v*2, l, m, idx, val)
    else:
        update(v*2+1, m+1, r, idx, val)
    tree[v] = merge(tree[v*2], tree[v*2+1])
    return tree[v]

def query(v, l, r, ql, qr):
    if ql <= l and r <= qr:
        return tree[v]
    m = (l + r) // 2
    if qr <= m:
        return query(v*2, l, m, ql, qr)
    if ql > m:
        return query(v*2+1, m+1, r, ql, qr)
    left = query(v*2, l, m, ql, qr)
    right = query(v*2+1, m+1, r, ql, qr)
    return merge(left, right)

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    global tree
    tree = [None] * (4 * n)

    build(a, 1, 0, n-1)

    out = []
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == "1":
            l, r = map(int, tmp[1:])
            l -= 1
            r -= 1
            res = query(1, 0, n-1, l, r)
            out.append(str(res.best if res.best > 0 else -1))
        else:
            i = int(tmp[1]) - 1
            x = int(tmp[2])
            update(1, 0, n-1, i, x)

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现在数组上构建线段树，并在更新后重新计算每个节点。 每个节点存储聚合信息并尝试维护在其间隔内看到的最佳有效段。 合并步骤使用左子级后缀和右子级前缀的受控枚举来显式检查所有跨越边界的子段。 尽管这在严格意义上不是渐近最优的，但它反映了预期的结构：有效性仅取决于总和和最大值，因此每个候选片段都可以在合并期间在本地进行验证。 

查询操作只是组合相关节点，更新向上传播更改。

 ## 边缘情况

 一种关键的边缘情况是当数组包含一个被许多小值包围的主导值时。 例如`[100,1,1,1,1,1]`。 天真的贪婪方法会失败，因为从左边延伸总是看起来无效，直到积累了足够的小值。 

该算法通过始终显式比较每个候选片段的总和和最大值来处理此问题，确保即使仅在跨越大边界后才出现有效性的片段仍会被评估。 

另一个边缘情况是对单个索引的重复更新。 由于更新在树中向上传播，因此每次仅影响 O(log n) 个节点，并且在受影响的路径之外不会发生重新计算泄漏，从而在所有查询中保持结构一致。
