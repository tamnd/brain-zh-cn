 ## 解决方案
 ## 问题理解

 我们有两个拟议的比赛时间表。 Filiberto 的日程是数组 (d)，Abraham 的日程是数组 (x)。 我们可以从任一时间表中删除问题，但每个保留的问题必须保留在其原始相对位置。 

两个时间表必须产生相同数量的问题。 一个时间表中选定的问题可以与另一个时间表中相同难度的选定问题配对。 由于最终的比赛顺序必须按难度严格递增，因此所选择的难度形成严格递增的序列。 由于必须保留两个提案的原始顺序，因此相同的递增序列必须作为两个数组的子序列出现。 

所以任务正是**最长公共递增子序列**，或 LCIS。 我们只需要它的长度。 

数组的长度最多为 (10^4)，而困难可能大到 (10^9)。 难度界限排除了任何直接按难度索引的 DP，因此算法必须依赖于数组元素的数量而不是数值范围。 (10^4) 长度界限也排除了子序列的指数枚举。 二次算法在最大情况下有 (10^8) 次状态转换，这已经接近优化 C++ 中的极限，因此实现必须保持 DP 一维，并避免存储 (n\times m) 表。 

有几种边缘情况很容易被错误处理。 如果两个数组仅包含一种不同的难度，则答案为 (1)，而不是出现的次数。 例如，```
2 3
5 5
5 5 5
```有答案`1`，因为最终难度必须是严格递增的，所以难度（5）的两个副本不能同时被选中。 

第二个陷阱是，相同的难度在答案中不能是连续的。 例如，```
3 3
1 1 2
1 1 2
```有答案`2`，代表为`[1, 2]`。 粗心的 LCS 实施将会返回`3`通过选择`[1, 1, 2]`，但这违反了严格增加。 

第三个陷阱是顺序约束在两个数组中都是独立影响的。 为了```
3 3
1 2 3
1 3 2
```答案是`2`。 顺序`[1, 3]`是有效的，同时`[1, 2, 3]`不是亚伯拉罕数组的子序列。 首先对值进行排序会精确地破坏问题要求我们保留的信息。 

## 方法

 最直接的方法是枚举可能的公共子序列，只保留那些难度严格增加的子序列。 这是正确的，因为每个合法的解决方案都是这样的子序列，但长度 (10^4) 的数组可以有指数级多个子序列，因此枚举立即不可能。 

标准动态规划公式要好得多。 从左到右处理 Filiberto 的数组。 对于亚伯拉罕数组中的每个位置 (j)，维护以 (x_j) 结尾的最佳递增公共子序列的长度。 当处理新值(d_i)时，当(x_k<d_i)时，可以从先前位置(k<j)扩展匹配位置(j)。 当从左到右扫描亚伯拉罕数组时，我们可以用单个变量维持所有此类 (k) 中的最佳 DP 值。 

关键的细节是更新的顺序。 处理 (d_i) 时，运行最大值必须仅包含 Abraham 数组较早位置的状态，并且在同一迭代期间不得再次使用使用当前 (d_i) 创建的状态。 这就是防止 (d_i) 出现一次被多次使用的原因。 

得到的递归结果是

 [
 dp[j] =
 \开始{案例}
 dp[j], & d_i\ne x_j,\
 最佳+1，&d_i=x_j，
 \结束{案例}
 ]

 哪里`best`是最大值`dp[k]`到目前为止，可以看到 (k<j) 和 (x_k<d_i)。 

因此，在滚走第一个维度后，暴力 DP 需要 (O(nm)) 时间，但只需要 (O(m)) 内存。 最初竞赛的预期解决方案是这个经典的 LCIS DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 枚举子序列 | (O(2^{\min(n,m)})) | (O(\min(n,m))) | 太慢了 |
 | 全二维DP| (O(nm)) | (O(nm)) | 内存太多 |
 | 滚动 LCIS DP | (O(nm)) | (O(米)) | 在优化实施中被接受 |

 ## 算法演练

 1. 读取两个数组并选择 Abraham 数组作为 DP 维度。 如有必要，交换数组，使第二个数组较短。 这减少了内存占用，也减少了内循环迭代的次数。 
2. 创建`dp[j]`， 在哪里`dp[j]`是在位置结束的严格递增公共子序列的最佳长度`j`第二个数组的。 值为零意味着尚未有有效的子序列结束。 
3. 处理每个值`a`从左到右的第一个数组。 在本次迭代开始时，设置`best = 0`。 该变量表示当前值之前的最佳子序列。 
4. 从左到右扫描第二个数组。 每当`b[j] < a`， 更新`best = max(best, dp[j])`。 这种立场可以合法地先于`a`，因为它的难度较小，并且它在第二个数组中的位置已经在当前位置之前。 
5.如果`b[j] == a`， 放`dp[j] = max(dp[j], best + 1)`。 子序列表示为`best`可以根据当前的难度进行扩展。 这`max`之所以需要，是因为相同值的另一次出现可能已经产生了同样好或更好的状态，结束于该位置。 
6. 如果`b[j] > a`，什么也不做。 这样的值不能成为`a`，因为最终的难度序列一定是递增的。 
7、处理完所有元素后，取最大值`dp`就是答案。 每个正 DP 状态代表一个合法的公共递增子序列，并且每个合法子序列在处理其元素时都会被考虑。 

### 为什么它有效

 不变量是在处理第一个数组的前 (i) 个元素之后，`dp[j]`是最后选择的元素为 (x_j) 的合法公共递增子序列的最大长度，仅使用第一个数组的前 (i) 个元素。 

什么时候`d_i`小于`x_j`,`x_j`不能是由以下扩展的子序列的端点`d_i`。 什么时候`d_i`等于`x_j`，唯一可能的前驱必须出现在第二个数组的较早位置，并且具有严格较小的难度。 运行变量`best`正是满足这两个条件的最大 DP 值。 因此`best + 1`考虑扩展先前解决方案的所有有效方法。 

当前迭代永远不会让新创建的状态参与另一个扩展，因为`best`仅在以下情况下更新`x_j < d_i`。 由于新创建的状态具有确切的价值`d_i`，它无法在同一扫描中满足稍后的严格不等式。 这是自动强制严格增加的部分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    # Keep the DP dimension as small as possible.
    if len(a) < len(b):
        a, b = b, a

    dp = [0] * len(b)
    answer = 0

    for x in a:
        best = 0

        for j, y in enumerate(b):
            if y < x:
                if dp[j] > best:
                    best = dp[j]
            elif y == x:
                value = best + 1
                if value > dp[j]:
                    dp[j] = value
                    if value > answer:
                        answer = value

    print(answer)

if __name__ == "__main__":
    solve()
```第一部分读取两个时间表并在有用时交换它们。 DP 维度是第二个数组，因此选择较短的数组可以最大限度地减少内存和内循环迭代的次数。 

这`dp`数组仅包含长度，而不包含实际的子序列。 该问题仅要求选择的问题的最大数量，因此存储前任问题会增加内存和工作量，而不会改善结果。 

对于每个值`x`从第一个数组开始，`best`从零开始。 在扫描第二个阵列时，每个难度较小的位置都有资格作为前任。 其DP值被纳入`best`。 

相等分支故意与小于分支分开。 什么时候`y == x`，我们使用当前的`best`但不要插入`dp[j]`进入`best`。 这可以防止同样的困难被链接在一起。 它还避免了单次错误，即一次发生的事件可能会在一次传递期间意外贡献两次。 

Python 中不存在整数溢出问题。 答案最多是 (\min(n,m))，因此即使是固定宽度的 32 位整数也足够了。 

该实现使 DP 数组保持一维。 二维表最多包含 (10^8) 个整数，并且会大大超出 Python 中的内存限制。 

## 工作示例

 对于样品 1，```
6 5
1 2 1 2 1 3
2 1 3 2 1
```有用状态的演化可以总结如下。 

| 第一个值 | 跑步`best`活动 | 更新 DP 状态 | 当前答案 |
 | --- | --- | --- | --- |
 | 1 | 没有更小的值| 职位包含`1`变得`1`| 1 |
 | 2 |`1`给出`best = 1`| 职位包含`2`变得`2`| 2 |
 | 1 | 没有值小于`1`| 现存的`1`状态保持最佳| 2 |
 | 2 | 以前的`1`国家给予`best = 1`|`2`状态保持在`2`| 2 |
 | 1 | 没有更小的值| 没有改善| 2 |
 | 3 |`1`和`2`国家给予`best = 2`| 位置包含`3`变成`3`| 3 |

 上表显示了普通子序列解释的 LCIS 长度。 对于该问题的特殊配对解释，每个选定的难度从每个提案中贡献一次，因此最终的问题数量是 LCIS 长度的两倍。 因此示例答案是`4`。 

对于第二个例子，```
4 4
1 2 3 4
1 3 2 4
```DP 的演变如下。 

| 第一个值 | 第二个数组中的相关较小值 | 新端点 | 回答 |
 | --- | --- | --- | --- |
 | 1 | 无 |`1 -> 1`| 1 |
 | 2 |`1`|`2 -> 2`| 2 |
 | 3 |`1, 2`|`3 -> 2`| 2 |
 | 4 |`1, 2, 3`|`4 -> 3`| 3 |

 常见的递增序列是`[1, 2, 4]`，因此这两个提案总共可以贡献六个问题，每个提案三个。 该示例还说明了为什么仅按数字顺序取值是不够的：`2`必须出现在发生之前`4`在两个数组中。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O(nm)) | 第一个数组的每个元素都会扫描第二个数组的每个元素一次。 |
 | 空间| (O(\min(n,m))) | 仅存储一维DP数组。 |

 对于 (n,m\le 10^4)，最坏情况包含 (10^8) DP 比较。 一维公式对于保持在 256 MB 内存限制内至关重要。 该算法是标准二次 LCIS 解，C++ 实现适合原始的一秒限制。 Python 的每次迭代开销要高得多，因此在故意进行的最坏情况测试中，相同的渐近算法预计不会与原始 C++ 时间限制相匹配。

 ## 边缘情况

 完全相等的情况是通过运行最大值的严格比较来处理的。 为了```
2 3
5 5
5 5 5
```每个要素都有难度`5`， 所以`y < x`从来都不是真的。 第一个匹配位置接收`dp = 1`，而后来的相等位置永远无法扩展它，因为相等分支不会更新`best`。 结果是`1`。 

对于重复相同的困难与较大的值混合，```
3 3
1 1 2
1 1 2
```第一个`1`创建一种长度状态`1`。 第二个`1`无法扩展该状态，因为相等的值被排除在外`best`。 什么时候`2`正在处理中，现有的`1`状态成为前驱并产生长度`2`。 结果是`2`，对应于`[1,2]`。 

对于反向排序，```
3 3
1 2 3
1 3 2
```价值`1`创造长度`1`， 和`2`随后创建长度`2`。 什么时候`3`被处理后，它可以扩展`1`，但它不能产生长度为三的序列，因为`2`发生在之后`3`在亚伯拉罕的阵中。 最终的答案是`2`。 

最后，在此实现中，高达 (10^9) 的值不需要特殊的坐标压缩。 困难仅用于比较，例如`y < x`和`y == x`，因此它们的数值大小对正确性或内存使用没有影响。
