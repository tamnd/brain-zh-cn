 ## 解决方案
 ## 问题理解

 我们有两个拟议的比赛时间表。 Filiberto 的日程表是一个长度为 (n) 的数组 (d)，而 Abraham 的日程表是一个长度为 (m) 的数组 (x)。 每个条目都是一个问题的难度，并且条目的位置是固定的，因为两个时间表都不能重新排列。 

如果我们选择一个难度（v），我们必须从每个数组中选择一个难度（v）的问题。 选定的两个问题在最终竞赛集中形成一对。 所选难度值必须从一对到另一对严格增加，而所选位置必须在两个原始数组内保持增加。 

所以如果选择的困难是

 [
 v_1 < v_2 < \dots < v_k,
 ]

 那么一定有位置

 [
 i_1 < i_2 < \点 < i_k
 ]

 在第一个数组中和

 [
 j_1 < j_2 < \点 < j_k
 ]

 在第二个数组中这样

 [
 d_{i_t}=x_{j_t}=v_t。 
]

 每个选定的难度都会贡献两个实际问题，每个提案中都有一个。 如果最长的可能序列包含 (k) 个困难，则所需的输出为 (2k)。 

这正是最长公共递增子序列问题，只不过答案最终必须乘以二。 

数组长度都可以达到(10^4)，因此可以有(10^8)对位置。 显式枚举所有对的算法在 C++ 中已经很大，指数搜索是完全不可能的。 标准动态规划解决方案使用 (O(nm)) 时间和 (O(\min(n,m))) 内存，这是该问题的实用二次解法。 难度值可以大到（10^9），但它们的大小不会影响DP，因为只需要相等和比较。 

一些边缘情况很容易导致错误的答案。 第一，重复出现的同样的困难不能全部计算在内。 例如，```
1 1
5
5
```有答案`2`，因为从每个数组中选择一个难度为 5 的问题。 将重复对视为两个困难的递增序列会错误地产生`4`。 

其次，仅仅有许多共同的困难是不够的。 它们在两个数组中的位置必须一致。 例如，```
2 2
1 2
2 1
```有答案`2`。 难度1和难度2都存在于两个数组中，但是以增加的难度选择它们需要两个数组中都是1在2之前，这是不可能的。 

第三，两个数组可能多次包含相同的难度，最佳出现次数取决于之前选择的内容。 例如，```
4 4
2 3 1 4
1 2 3 4
```有答案`6`，使用困难（2,3,4）。 总是选择当前可用的最小难度的贪心策略会首先选择 1，并且仅获得两个难度：1 和 4。 

最后，如果数组根本没有共同的困难，那么答案是零。 为了```
2 2
1 2
3 4
```没有任何东西可以配对，所以正确的输出是`0`。 

## 方法

 直接的暴力方法将生成第一个数组的每个子序列和第二个数组的每个子序列，然后检查哪些对形成相同的严格递增序列。 一个数组中有 (2^n) 个子序列，另一个数组中有 (2^m) 个子序列，因此即使仅考虑候选子序列对也会给出 (\Theta(2^{n+m})) 种可能性。 在最大大小下，它变为 (2^{20000})，这远远超出了任何可执行文件。 

有用的观察是我们不需要记住整个选定的序列。 假设我们从左到右处理第一个数组。 对于第二个数组中的每个位置 (j)，我们可以存储正好在 (x_j) 处结束的公共递增序列的最佳长度。 当考虑当前值 (d_i) 时，每个较早的 (x_j) 且 (x_j<d_i) 都是有效的前驱。 在所有这样的位置中，我们只需要最大的DP值。 如果 (d_i=x_j)，我们可以将 (d_i) 附加到该最佳前驱。 

微妙的部分是从左到右处理第二个数组。 我们维护一个变量`best`，表示已访问过的位置中严格小于当前值（d_i）的最大DP值。 当(d_i=x_j)时，新的候选者是`best + 1`。 当(x_j<d_i)时，`dp[j]`成为合格的前任并可以更新`best`。 当 (x_j>d_i) 时，它不能是前驱，因为所得的难度序列不会严格递增。 

DP 在扫描第二个阵列时更新，因此会自动考虑该阵列中的位置。 外循环扫描第一个数组，因此那里的位置也受到尊重。 相同的值永远不会包含在`best`，它给出严格的递增顺序而不是非递减顺序。 

由此产生的算法是经典的一维 LCIS 动态规划技术。 我们只需要长度，而不需要实际的难度序列，因此整个（n\times m）表可以压缩为一个数组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(2^{n+m})) 或更糟 | 指数| 太慢了 |
 | 最佳| (O(nm)) | (O(\min(n,m))) | 已接受 |

 ## 算法演练

 1. 存储两个难度数组。 我们可以选择使第一个数组较短，因为 DP 数组的第二个数组的每个元素都有一个条目。 当输入大小不同时，这不会改变正确性并减少内存。 
2. 创建`dp[j]`， 在哪里`dp[j]`是一个常见严格递增序列的最大长度，其最后选择的难度为`b[j]`。 零表示当前没有有效序列结束。 
3. 处理每个值`a[i]`从左到右。 在扫描第二个数组之前，设置`best = 0`。 该变量将包含以第二个数组的已处理位置结束的最佳序列长度，其难度小于`a[i]`。 
4. 扫描`b`从左到右。 如果`b[j] < a[i]`， 然后`b[j]`可以先于`a[i]`，所以更新`best`和`dp[j]`。 
5.如果`b[j] == a[i]`，则可以匹配两个当前元素。 以此值结束的最佳序列具有长度`best + 1`，所以更新`dp[j]`具有该值。 
6. 如果`b[j] > a[i]`，没有任何变化。 这样的值不能先于`a[i]`按严格递增的顺序。 
7. After all elements of the first array have been processed, the largest value in`dp`是 LCIS 的长度 (k)。 每个选定的难度对应于每个数组中选定的一个问题，因此打印`2 * k`。 

关键的不变量是，在外循环的每个点，`dp[j]`表示从第一数组的已处理前缀和与第二数组的位置(j)相关的已处理前缀可获得的最佳有效序列。 扫描一行时，`best`恰好包含最大值`dp[j]`难度小于当前第一数组值的位置。 因此，每个转换都精确地考虑有效的前驱，而不考虑无效的前驱。 由于每个可能的LCIS都可以通过其最终匹配对来查看，因此DP最终会考虑最佳的最终对，因此最大存储长度恰好是所选难度的最佳数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    # Keep the DP array on the shorter sequence.
    if len(b) > len(a):
        a, b = b, a

    dp = [0] * len(b)
    answer = 0

    for x in a:
        best = 0

        for j, y in enumerate(b):
            if y < x:
                if dp[j] > best:
                    best = dp[j]
            elif y == x:
                candidate = best + 1
                if candidate > dp[j]:
                    dp[j] = candidate
                    if candidate > answer:
                        answer = candidate

    print(answer * 2)

if __name__ == "__main__":
    solve()
```第一部分阅读两个拟议的时间表。 必要时交换数组是安全的，因为问题是对称的：公共递增子序列必须尊重两个数组，无论哪个数组称为第一个数组。 

这`dp`数组为较短数组的每个位置存储一个值。 外部循环修复另一个数组的问题，而内部循环检查第二个数组中可能的匹配位置。 

内循环内两个条件的顺序很重要。 为了`y < x`,`dp[j]`成为候选人`best`。 为了`y == x`，使用当前值进行匹配`best`从严格较小的值累积。 因为`best`仅针对较小的值进行更新，相等的值永远不能扩展另一个相等的值。 这正是严格增加条件所需要的。 

我们不更新`best`处理等值后。 这样做将允许当前值用作在同一扫描期间再次出现相同值的前驱值，这将错误地将严格不等式转变为非严格不等式。 

更新内容`dp[j] = max(dp[j], best + 1)`也是必要的，因为可以从第一个数组的不同前缀到达第二个数组中的相同位置。 我们保留最强的可能性。 

最终答案乘以二是因为`dp`计算选定的难度值，而问题则要求选定问题的总数。 共同递增序列中的每个困难都恰好贡献了每个提案中的一个问题。 

Python 整数对于这些值不会溢出，并且 DP 值最多为 (10^4)。

 ## 边缘情况

 当两个数组只包含一个相同的问题时，例如```
1 1
7
7
```DP 以全零开头。 当第一个且唯一的值匹配时，`best`为零，因此匹配位置接收`dp = 1`。 LCIS 包含一个困难，算法打印 (1\cdot2=2)。 

当两个阵列都没有出现困难时，```
2 2
1 2
3 4
```没有达到任何平等分支。 每一个`dp`输入保持为零，因此最大 LCIS 长度为零，最终答案为`0`。 

对于重复的相等值，```
3 4
7 7 7
7 7 7 7
```第一个`7`创建一个长度为 1 的序列。 以后每隔一段时间`7`没有看到严格更小的值，因为条件`y < x`对于另一个人来说是假的`7`。 因此，任何过渡都不能产生长度二。 最终LCIS长度为1，答案为`2`。 

排序问题出现在```
4 4
2 3 1 1000000000
1 2 3 1000000000
```常见的递增序列（2,3,10^9）是有效的。 第一个数组使用位置 (1,2,4)，第二个数组使用位置 (2,3,4)。 价值`1`也很常见，但首先选择它会将其出现在第一个数组的位置 3 中，从而使后面的`2`和`3`不可用。 民主党并不贪婪地承诺`1`; 它保留所有相关状态并找到长度三，产生`6`。 

相同的机制处理最大尺寸重复值的情况。 拥有 10,000 份`5`在每个数组中，第一个匹配的出现给出长度一，而随后的每个相同出现都被阻止扩展它，因为`best`只包含严格较小的困难。 结果依然`2`，无论存在多少相同难度的副本。
