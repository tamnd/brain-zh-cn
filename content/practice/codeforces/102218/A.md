 ## 解决方案
 ## 问题理解

 我们得到一串小写英文字母，我们可以按任意顺序重新排列它的字符。 艾伦从字典中最小的字符串到最大的字符串搜索他的字典，因此最好的礼物是在该顺序​​中尽早出现的重新排列。 

字典顺序上最小的重新排列只是将所有字符按字母顺序递增排列的字符串。 例如，以下字符`mac`只能重新排列成字符串，例如`mac`,`mca`,`amc`，等等，以及`acm`按字典顺序排列是第一个。 

长度可以达到（10^7），这比昂贵的算法在大约一秒的时间限制下舒适的大小要大得多。 (O(N^2)) 算法在上限上需要大约 (10^{14}) 次操作，而 (O(N!)) 枚举远远超出了这个范围。 当 (N=10^7) 时，即使基于比较的 (O(N\log N)) 排序也会执行数亿次比较。 关键的额外信息是每个字符都属于只有 26 个小写字母的字母表。 

第一个边缘情况是单字符字符串。 用于输入`1`其次是`z`，答案仍然是`z`。 无需重新排列，并且假设至少两个字符的实现可能会引入不必要的边界错误。 

第二个边缘情况是重复字符。 用于输入`5`其次是`aaaaa`，答案是`aaaaa`。 将相同字符视为不同对象的粗心实现可能会执行冗余工作，尽管结果必须包含完全相同的五个副本。 

第三种边缘情况是最小字符多次出现的混合情况。 用于输入`6`其次是`zzabca`，答案是`aabcz z`， 或者`aabczz`没有空间。 两人`a`两个字符都必须出现在每个较大字符之前。 仅移动最小字符一次的实现会产生错误的顺序。 

## 方法

 直接的暴力方法将生成字符串的所有可能的重新排列，对它们进行比较，并保留字典顺序上最小的一个。 当所有字符都不同时，有 (N!) 种排列。 比较两个字符串最多可以检查 (N) 个字符，因此最坏情况的工作是 (O(N\cdot N!))。 在 (N=10^7) 处，即使写下这些排列的前一小部分也是不可能的。 重复的字符减少了不同排列的数量，但最坏的情况原则上仍然是所有字符都不同，并且输入字母表限制不能挽救大（N）的排列枚举。 

一种更明智的通用方法是比较排序。 如果我们按升序对字符进行排序，结果正是字典顺序上最小的重新排列。 这需要与标准比较排序进行 (O(N\log N)) 次比较。 这是正确的，但约束 (N\le 10^7) 使得额外的对数因子不必要地昂贵，特别是在原始问题使用的 1.25 秒限制下。 

关键的观察结果是只有 26 个可能的字符。 我们不需要发现数百万个单个字符的相对顺序，因为它们的字母顺序是已知的。 我们只需要数一下有多少`a`字符存在，那么有多少个`b`字符存在，等等`z`。 一旦知道了这 26 个频率，就可以通过按字母顺序写出每个字符的计数次数来获得答案。 

这是最简单形式的计数排序。 我们不需要花费 (O(N\log N)) 来比较顺序已知的字符，而是扫描一次输入并使用 26 个计数器的固定数组。 构建答案也需要 (O(N))，因此整个算法是线性的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 枚举所有重新排列 | (O(N\cdot N!)) | (O(N)) | 太慢了|
 | 比较排序| (O(N\log N)) | (O(N)) | 不必要的昂贵|
 | 计算字符 | (O(N)) | (O(N)) 用于输入/输出，(O(26)) 辅助 | 已接受 |

 ## 算法演练

 1. 读取 (N) 和字符串 (S)。 (N) 的值告诉我们预期的字符数，而实际字符串包含我们必须重新排列的字符。 
2. 创建 26 个计数器，每个小写字母对应一个计数器。 对于 (S) 中的每个字符，递增与其字母位置相对应的计数器。 由于只有 26 个可能的位置，因此可以在恒定时间内对每个字符进行分类。 
3.遍历26个计数器`a`通过`z`。 对于频率为 (f) 的字符，将该字符恰好附加 (f) 次到结果中。 在字典顺序最小的字符串中，较小字符的所有副本必须位于较大字符的每个副本之前。 
4. 写入结果字符串。 每个输入字符都被精确计数一次，然后发出一次，因此输出是原始字符串的重新排列。 

### 为什么它有效

 计数后，算法准确地知道输入中每个字母出现了多少个副本。 假设生成的字符串在较小字符之前有一个较大的字符。 交换这两个位置将使字符串按字典顺序变小，同时保留所有字符频率。 因此，这种倒置不可能发生在字典顺序上最小的重新排列中。 唯一没有这种反转的安排是所有的安排`a`字符先行，然后是所有字符`b`人物等`z`。 该算法准确地构造了这种排列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    count = [0] * 26

    for ch in s:
        count[ord(ch) - ord('a')] += 1

    result = []
    for i, freq in enumerate(count):
        if freq:
            result.append(chr(ord('a') + i) * freq)

    sys.stdout.write(''.join(result))

if __name__ == "__main__":
    solve()
```第一行读取声明的长度，尽管算法在读取输入后不需要使用它。 保留该值对于匹配输入格式很有用，而迭代实际字符串可以避免对超出语句保证的行边界进行假设。 

表达式`ord(ch) - ord('a')`将小写字母转换为 0 到 25 之间的索引。例如，`a`变为0，`b`变为 1，并且`z`变为 25。因此，无论字符串包含十个字符还是一千万个字符，计数器数组都只需要 26 个条目。 

结果是由诸如`a * 3`或者`m * 2`。 这比一次重复连接一个字符更好，因为重复的字符串连接可能会产生不必要的复制。 该列表最多包含 26 个字符串，并且`''.join(result)`将它们合并到最终输出中一次。 

Python 中整数不能溢出。 最大的计数器只有(10^7)，很容易用Python整数表示。 

这`.strip()`调用删除产生的换行符`readline()`。 由于输入仅包含小写字母，因此不需要保留有意义的空格。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O(N)) | 输入被扫描一次，并且 26 个计数器以恒定的字母大小发出。 |
 | 空间| (O(N)) | 输入字符串和结果输出占用线性空间，而频率数组仅使用 26 个计数器。 |

 当 (N) 与 (10^7) 一样大时，线性处理是合适的目标。 该算法对每个输入字符执行恒定量的工作，并且从不分配与可能的排列数量成比例的数据结构。 辅助计数状态保持固定为26个条目，这特别适合原来的64MB内存限制。 

## 测试用例```python
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    s = input().strip()

    count = [0] * 26

    for ch in s:
        count[ord(ch) - ord('a')] += 1

    result = []
    for i, freq in enumerate(count):
        if freq:
            result.append(chr(ord('a') + i) * freq)

    sys.stdout.write(''.join(result))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("3\nmac\n") == "acm", "sample 1"
assert run("4\ngeso\n") == "egos", "sample 2"

# Minimum-size input
assert run("1\nz\n") == "z", "single character"

# All characters are equal
assert run("7\naaaaaaa\n") == "aaaaaaa", "all equal"

# Boundary alphabet characters and repeated letters
assert run("8\nzzzzaaaa\n") == "aaaazzzz", "alphabet boundaries"

# Maximum-size input
s = "a" * 10_000_000
assert run(f"{len(s)}\n{s}\n") == s, "maximum size"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`1`/`z`|`z`| 最小尺寸且无需重新排列的情况 |
 |`7`/`aaaaaaa`|`aaaaaaa`| 重复字符和频率统计|
 |`8`/`zzzzaaaa`|`aaaazzzz`| 最小和最大的字母字符，包括重复块 |
 |`10000000`/千万`a`人物 | 同样的一千万`a`人物 | 最大输入尺寸和线性处理|

 最大尺寸断言是故意构造的，而不是写成一千万字符的行。 在实际的比赛提交中，只有裁判输入需要包含该数据，而测试则以编程方式表达相同的边界条件。 

## 边缘情况

 对于单字符的情况，请考虑：```
1
z
```计数器为`z`变为 1，并且所有其他计数器保持为零。 发射阶段跳过空字母并输出一个`z`。 没有第二个字符的索引，因此自然处理 (N=1) 处的边界。 

对于重复的字符，请考虑：```
5
aaaaa
```每次迭代都会增加相同的计数器，留下`count['a'] = 5`。 输出相发射`a * 5`，生产`aaaaa`。 不需要不同的排列逻辑，因为频率表示已经捕获了与答案相关的整个状态。 

对于重复的最小字符与较大字符混合，请考虑：```
6
zzabca
```计数器变成`a:2`,`b:1`,`c:1`， 和`z:2`。 发射顺序是`aa`， 然后`b`， 然后`c`， 然后`zz`，生产：```
aabczz
```仅从一个开始的重新排列`a`， 例如`abaczz`，不能是最优的，因为另一个`a`存在并将其放置在第一个之后`a`使字符串变小。 

对于字母表边界情况，请考虑：```
4
zaba
```频率是`a:2`,`b:1`， 和`z:1`。 该算法发出`a`先阻塞，然后`b`， 然后`z`，生产：```
aabz
```这证实了该算法不依赖于输入顺序并正确处理小写字母的两端。 

最大尺寸的情况遵循完全相同的逻辑。 如果所有 (10^7) 个字符都是`a`，扫描执行 (10^7) 个恒定时间计数器增量，并且输出阶段发出一个 (10^7) 个字符块。 没有排序步骤，也没有尝试枚举排列，因此运行时间随着实际输入大小线性增长。
