 ## 解决方案
 ## 问题理解

 我们给出了两个正整数 (A) 和 (B)，但它们可能非常长，因为第一行给出了它们的位数，而不是机器大小范围内的数值。 我们还给出了一个十进制字符串 (P)，它应该等于 (A \times B)，只不过其中一位数字已被替换为`*`。 缺失的数字保证是 (1,\dots,9) 之一，我们需要打印它。 

关键的约束是 (a)、(b) 和 (p) 可以接近 (10^6)。 这意味着 (A)、(B) 和 (P) 可以包含大约一百万个字符。 我们无法将它们转换为普通整数，甚至将两百万位整数与教科书乘法相乘也需要大约 (10^{12}) 个单位数运算。 0.5秒的时间限制使得任何二次算法完全不适合。 我们需要对输入进行线性扫描。 

有几种边缘情况可能会导致看似合理的实施失败。 缺失的数字可能是数字 (9)。 例如，```
1 1 2
7
3
2*
```乘积是 (21)，所以答案是 (1)，而不是 (0) 的余数。 更一般地，当模 (9) 的计算产生 (0) 时，唯一有效的缺失数字是 (9)，因为 (0) 本身是禁止的。 

这`*`也可以是产品的第一个字符。 例如，```
2 2 3
10
10
*00
```答案是（1）。 尝试将不完整乘积解析为整数的方法必须专门处理前导通配符，而数字和方法不关心通配符出现的位置。 

该乘积也可以比标准整数类型大得多。 例如，如果 (A) 和 (B) 各有数十万位数字，则显式构造 (A \times B) 是不可行的。 下面的解决方案从不构造乘积，只需要 (P) 的已知部分的数字和。 

## 方法

 直接的暴力方法会尝试从 (1) 到 (9) 的每个可能丢失的数字。 对于每个候选人，它将替换`*`，构造完整的乘积字符串，并检查它是否等于（A \times B）。 这个想法是正确的，因为该声明保证了只有一个候选者是真正缺失的数字。 

问题是乘法。 如果 (A) 和 (B) 都包含 (10^6) 个数字，则普通教科书乘法需要 (O(10^{12})) 个数字运算。 尝试九个候选者并不会改变渐近问题，因此这种方法远远超出了时间限制。 

关键的观察是十进制数字和保留模 (9) 的值。 对于每个整数 (X)，

 [
 X \equiv \text{}X \pmod 9 的数字之和。 
]

 由于 (P=A\times B)，我们知道

 [
 P \equiv A\times B \pmod 9。 
]

 假设(P)的已知数字有(S)，缺少的数字是(d)。 然后

 [
 S+d \equiv A\times B \pmod 9。 
]

 我们可以通过扫描 (A\bmod 9) 和 (B\bmod 9) 的数字来计算它们，而无需构造它们的数值。 我们还可以通过扫描 (P) 来计算 (S\bmod 9)。 因此，通过对所有输入字符进行一次线性传递来确定丢失的数字。 

(d\neq0) 的保证消除了唯一的歧义。 (1)到(8)的余数直接给出对应的数字，而余数(0)必须代表数字(9)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(ab)) | (O(a+b+p)) | 太慢了 |
 | 最佳 | (O(a+b+p)) | (O(a+b+p)) 用于输入存储，(O(1)) 辅助 | 已接受 |

 ## 算法演练

 1. 读取位数和三个字符串。 计算本身不需要计数，但读取字符串是必要的，因为数字对于本机整数类型来说可能太大了。 
2. 通过处理 (A) 的每个数字来计算 (A\bmod9)。 如果当前余数为 (r)，下一位为 (x)，则新余数为

 [
 (10r+x)\bmod9。 
]

 因为(10\equiv1\pmod9)，这相当于简单地加上数字模(9)。 

1. 以同样的方式计算(B\bmod9)。 
2. 扫描 (P) 并添加除`*`到模 (9) 的运行总和。 的位置`*`并不重要，因为只需要剩余数字的总和。 
3.设(r=(A\bmod9)(B\bmod9)\bmod9)。 这是完整产品的残留物。 
4. 缺失的数字必须满足

 [
 d\equiv r-S\pmod9。 
]

 将结果标准化为范围 (0,\dots,8)。 

1. 如果所得余数为 (0)，则打印 (9)。 否则打印残留物本身。 由于缺失的数字保证为非零，因此残数 (0) 不能对应于数字 (0)，而将 (9) 保留为唯一的有效答案。 

### 为什么它有效

 不变量是每个数字及其十进制数字之和具有相同的模 (9) 余数。 在 (A) 和 (B) 的扫描过程中，我们保持它们精确的残基模 (9)。 在扫描 (P) 期间，我们保留所有已知乘积数字的余数。 如果缺失的数字是(d)，则(P)的完整数字和是(S+d)，因此它必须具有与(A\times B)相同的余数。 因此，计算值 (d\equiv A B-S\pmod9) 是唯一可能缺失的模 (9) 数字。 数字 (1) 到 (9) 代表每个余数模 (9) 一次，其中 (9) 代表余数 (0)，因此答案是唯一确定的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def mod9(s):
    r = 0
    for ch in s:
        r = (r + ord(ch) - ord('0')) % 9
    return r

def solve():
    a, b, p = map(int, input().split())
    A = input().strip()
    B = input().strip()
    P = input().strip()

    ra = mod9(A)
    rb = mod9(B)

    known = 0
    for ch in P:
        if ch != '*':
            known = (known + ord(ch) - ord('0')) % 9

    missing = (ra * rb - known) % 9

    if missing == 0:
        missing = 9

    print(missing)

if __name__ == "__main__":
    solve()
```这`mod9`函数实现前两个算法步骤。 它永远不会将整个字符串转换为整数，因此其中间值保持在 (9) 以下。 直接使用数字和是有效的，因为 (10\equiv1\pmod9)。 

产品字符串被单独扫描，以便`*`被忽略而不是被意外地视为数字。 表达式`(ra * rb - known) % 9`使用 Python 的模运算自动标准化负差。 

Python 中不存在整数溢出问题，即使在固定宽度语言中，用于模计算的唯一值也最多是 (8)。 唯一可能较大的对象是三个输入字符串本身。 声明的位数不用于索引字符串，因此不存在与乘积长度相关的差一问题。 

## 工作示例

 对于第一个样本，```
1 1 2
3
8
2*
```我们得到以下状态。 

| 步骤| (A\bmod9) | (B\bmod9) | 已知产品残留| 缺失残留|
 | ---| ---| ---| ---| ---|
 | 阅读 (A=3) | 3 | | | |
 | 阅读 (B=8) | 3 | 8 | | |
 | 读取已知数字`2`| 3 | 8 | 2 | |
 | 计算产品残留量 | 3 | 8 | 2 | (3\cdot8-2=22\equiv4) |
 | 输出| 3 | 8 | 2 | 4 |

 实际乘积是 (24)，因此缺少的数字是 (4)。 该迹证明了中心不变量：(24\equiv2+4\equiv6\pmod9)。 

对于第二个样本，```

10

```痕迹是：

 | 步骤| (A\bmod9) | (B\bmod9) | 已知产品残留| 缺失残留|

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(a+b+p)) | (A)、(B) 和 (P) 的每个数字都被扫描一次。 |
 | 空间| (O(a+b+p)) | 输入的字符串被存储； 算法本身使用 (O(1)) 辅助空间。 |

 每个输入数字大约有一百万位，线性扫描仅执行几百万次简单操作。 这与预期的约束兼容，而显式乘以大整数将需要二次工作，并且在 0.5 秒限制下不可行。

 ## 边缘情况

 零残留的情况是最微妙的。 考虑```
1 1 2
7
3
1*
```这里(A\bmod9=7)，(B\bmod9=3)，所以乘积有余数(21\bmod9=3)。 已知数字贡献 (1)，给出 (d\equiv3-1\equiv2\pmod9)。 该算法打印 (2)，匹配 (7\times3=21)。 如果所需的数字是 (9)，则计算出的余数将为 (0)，并且从 (0) 到 (9) 的最终转换可以处理这种情况。 

开头的通配符不需要单独的分支。 为了```
2 2 3
10
10
*00
```两个操作数都有留数 (1)，因此它们的乘积有留数 (1)。 已知数字之和为 (0)，给出 (d=1)。 该算法从不尝试解析`*00`，所以不存在主角问题。 

当通配符位于中间或末尾时，同样的推理也适用。 例如，在```
3 3 5
111
111
12*21
```操作数有残数 (3) 和 (3)，得到乘积残数 (0)。 已知乘积数字之和为(6)，这也是余数(6)。 因此缺失的数字满足(d\equiv0-6\equiv3\pmod9)，所以答案是(3)。 实际产品是（12321）。 

最后，很长的操作数不会改变方法。 如果 (A) 有 (999999) 个数字，算法仍然对每个数字执行一次模块化更新。 它从不将百万位整数存储为数字对象，也从不对这些数字执行乘法。 产品本身仅通过同余模 (9) 间接表示，这正是识别单个缺失的非零数字所需的信息。
