 ## 解决方案
 ## 问题理解

 给定两个正整数 (A) 和 (B)，每个整数可能包含最多一百万个十进制数字。 他们的乘积被写成十进制字符串（P），只不过其中一位数字被替换为`*`。 任务是恢复丢失的数字。 丢失的数字保证非零。 

第一行给出 (A)、(B) 和 (P) 的长度。 接下来的两行包含 (A) 和 (B)，最后一行包含 (A \times B) 的部分已知十进制表示形式。 答案是必须替换的单个十进制数字`*`。 

关键的约束是位数，而不是整数的数值。 (A) 和 (B) 各自可以有 (10^6) 位数字，因此用普通机器算术构造任一整数是不可能的。 即使是一个小学乘法也需要 (10^{12}) 位的运算。 尝试所有九个可能丢失的数字并检查所得的结果将使成本乘以九。 

输入本身最多可以包含大约两百万个数字，因此扫描字符串固定次数的算法是合适的。 需要乘法、转换为内置整数类型或对数字字符串进行二次运算的算法是不合适的。 Python 的任意精度整数不会改变这个结论，因为输入整数可能远远大于实际的本机表示形式，并且转换百万位十进制字符串本身就是不必要的工作。 

有两种边缘情况通常会导致错误。 首先，缺失的数字可能是（9）。 例如，```
1 1 2
9
1
1*
```给出 (A \times B = 9)，所以答案是`9`。 仅计算结果模 (9) 并直接返回余数的方法将返回`0`，这是被禁止的，但在数学上等效于模 (9)。 缺失数字非零的保证告诉我们将残数 (0) 解释为数字 (9)。 

第二个边缘情况是产品两端缺少数字。 例如，```
2 2 3
10
10
*00
```有产品`100`，所以缺失的数字是`1`。 尝试仅使用相邻字符来推断数字或将星号视为内部数字的方法在这里可能会失败。 模参数不依赖于星形的位置，因此相同的计算适用于第一个、最后一个或任何中间位置。 

## 方法

 直接的方法是尝试从 (1) 到 (9) 的每个可能的非零数字，替换`*`与该数字，并测试结果字符串是否等于（A \times B）。 这是正确的，因为丢失的数字保证是这九个值之一，因此测试所有可能性必须找到答案。 

问题是乘法。 (A) 和 (B) 中最多 (10^6) 位数字，普通长乘法对一位候选者需要 (O(10^{12})) 位数字运算。 在最坏的情况下，测试九个候选者仍然留下大约（9 \times 10^{12}）个操作。 更复杂的大整数乘法可以渐近地减少这个问题，但是这个问题有一个更简单的属性，可以完全避免乘法。 

关键的观察结果是，当十进制数的数字相加时，它们的值会保留模 (9) 的值。 对于任何十进制数 (X)，

 [
 X \equiv \sum \text{数字}(X) \pmod 9.
 ]

 由于 (P = A \times B)，我们可以计算

 [
 P \bmod 9 = (A \bmod 9)(B \bmod 9) \bmod 9。 
]

 我们可以通过扫描 (A \bmod 9) 和 (B \bmod 9) 的数字来计算它们，而无需构造巨大的整数。 我们还可以计算（P）每个已知数字的贡献，只留下未知数字（x）。 

假设(P)中已知数字的总和是(S)。 然后

 [
 x + S \equiv A \times B \pmod 9。 
]

 因此

 [
 x \equiv (A \time B - S) \pmod 9.
 ]

 这给出了从 (0) 到 (8) 的余数。 如果是 (1) 到 (8)，则正是缺少的数字。 如果是 (0)，则缺失的数字一定是 (9)，因为问题明确排除了 (0)。 

蛮力方法之所以有效，是因为可以根据精确的乘积检查每个候选者，但当操作数包含数百万位数字时，就会失败。 观察到十进制数字和保留模 (9) 的值，让我们可以用三个线性扫描代替巨大的乘法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(AB)) 用于小学乘法，最多重复 9 次 | (O(A+B+P)) | 太慢了|
 | 最佳| (O(A+B+P)) | (O(1)) 除了输入字符串 | 已接受 |

 这里复杂度表达式中的(A)、(B)和(P)表示位数，而不是整数的数值。 

## 算法演练

 1. 读取三个长度以及代表 (A)、(B) 和部分已知乘积 (P) 的字符串。 数学不需要长度，但阅读它们会遵循输入格式。 
2. 通过扫描 (A) 的每个数字并重复应用来计算 (A \bmod 9)`remainder = (remainder + digit) % 9`。 对 (B) 进行相同的计算。 这是有效的，因为小数位的值为 (10^k) 和 (10 \equiv 1 \pmod 9)，因此 (10) 的每个幂也与 (1) 全等。 
3. 将两个余数乘以模 (9)。 结果是完整产品 (P) 必须具有的余数。 
4. 扫描 (P)，将每个已知数字加上模 (9)，同时忽略`*`。 调用结果值`known`。 
5. 计算缺失数字的残数为`(product_mod - known) % 9`。 模运算处理减法为负的情况。 
6. 如果所得残差为零，则输出`9`; 否则输出残差本身。 余数零对应于两个数字`0`和数字`9`，并且该声明排除了`0`。 

### 为什么它有效

 不变量是每个处理后的十进制字符串与处理后的数字之和具有相同的模 (9) 余数。 扫描（A）和（B）后，我们知道它们精确的模（9）留数，因此可以通过模乘知道它们的乘积留数。 扫描 (P) 的已知数字后，其数字和中唯一缺少的贡献是未知数字 (x)。 因此 (x + S) 必须精确地具有乘积的模 (9) 余数。 计算出的残差在允许的数字 (1,\ldots,9) 中唯一标识 (x)，因为只有 (0) 和 (9) 共享残差零，而 (0) 是被禁止的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def digit_mod_9(s):
    remainder = 0
    for ch in s:
        if ch != '\n':
            remainder = (remainder + ord(ch) - ord('0')) % 9
    return remainder

def solve():
    a_len, b_len, p_len = map(int, input().split())

    A = input().strip()
    B = input().strip()
    P = input().strip()

    a_mod = digit_mod_9(A)
    b_mod = digit_mod_9(B)

    product_mod = (a_mod * b_mod) % 9

    known_mod = 0
    for ch in P:
        if ch != '*':
            known_mod = (known_mod + ord(ch) - ord('0')) % 9

    missing = (product_mod - known_mod) % 9

    if missing == 0:
        missing = 9

    print(missing)

if __name__ == "__main__":
    solve()
```这`digit_mod_9`函数执行算法第一部分中描述的数字和计算。 保持模 (9) 的余数减少意味着变量的增长永远不会超过一位数。 

The two calls on`A`和`B`提供操作数的余数。 将这些残数相乘即可得到实际乘积的残数，而无需构建该乘积。 

最终扫描会跳过`*`并累加所有已知乘积数字的余数。 从乘积余数中减去该值就可以分离出缺失的模 (9) 数字。 

这`% 9`减法之后的运算是必要的，因为 Python 在取模之前可能会产生负的中间结果。 最终转换自`0`到`9`也是必不可少的。 只要实际缺失的数字是 (9)，直接返回余数就会失败。 

没有整数转换，也没有大数乘法。 Python 的任意精度算术仅适用于 (9^2) 以下的微小值，因此整数溢出不是问题。 

## 工作示例

 对于第一个样本，输入是：```
1 1 2
3
8
2*
```计算过程如下。 

| 变量| 状态|
 | --- | --- |
 | (A \bmod 9) | (3) |
 | (B \bmod 9) | (8) |
 | 乘积模 (9) | (3 \times 8 \bmod 9 = 6) |
 | 已知乘积数字和模 (9) | (2) |
 | 缺少数字模 (9) | (6 - 2 = 4) |
 | 回答 |`4`|

 实际乘积为 (3 × 8 = 24)。 模计算达到相同的缺失数字，而无需显式计算该乘积。 此处可以看到不变量，因为 (2 + 4 = 6) 与乘积的余数模 (9) 相匹配。 

对于第二个样本，输入是：```
2 2 3
10
10
*00
```踪迹是：

 | 变量| 状态|
 | --- | --- |
 | (A \bmod 9) | (1) |
 | (B \bmod 9) | (1) |
 | 乘积模 (9) | (1) |
 | 已知乘积数字和模 (9) | (0) |
 | 缺少数字模 (9) | (1) |
 | 回答 |`1`|

 这里的星星是产品的第一个字符。 它的位置对方法没有影响，因为每个十进制数字都会贡献其模 (9) 的值，而不管其位值如何。 该产品是`100`，其余数为 (1)，因此缺失的前导数字必定是`1`。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O(A+B+P)) | 每个输入的数字和产品字符串都会被扫描一次。 |
 | 空间| (O(A+B+P)) | 输入字符串被存储，而算法本身使用 (O(1)) 额外空间。 |

 总输入大小最多为几百万个字符，因此即使在非常紧张的时间限制下，恒定数量的线性扫描也是合适的。 该算法从不分配完整产品的表示，并且仅使用输入字符串之外的几个小整数变量，这也使内存使用量保持在规定的限制内。

 ## 边缘情况

 缺失数字等于 (9) 是最微妙的情况。 考虑：```
1 1 1
1
9
*
```该产品是`9`，其模 (9) 的余数为零。 已知的数字贡献也为零，因为没有已知的乘积数字。 该算法计算`missing = 0`，然后将该残差转换为`9`。 这是正确的，因为`0`被输入保证所禁止。 

产品开头的星星不需要特殊的位置处理。 为了：```
2 1 2
12
8
*6
```该产品是`96`。 我们有 (12 \equiv 3 \pmod 9) 和 (8 \equiv 8 \pmod 9)，给出产品残差 (3 \times 8 \equiv 6)。 已知的数字是`6`，因此缺失的数字有残数 (6-6\equiv0)。 唯一允许带有该残基的数字是`9`，给出正确的产品`96`。 

末尾的星星表现相同。 为了：```
1 1 2
3
8
2*
```乘积余数为(6)，而已知数字`2`贡献（2）。 缺少的数字是 (4)，因此算法打印`4`。 

处理大操作数时无需将它们相乘。 如果 (A) 包含一百万位且 (B) 包含一百万位，则算法在扫描输入时仅保留 (0) 到 (8) 范围内的两个残基。 同样的推理也适用于包含近两百万位数字的产品字符串。 这正是模块化方法成功而显式乘法失败的规模。
