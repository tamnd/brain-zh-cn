 ## 解决方案
 ## 问题理解

 我们有几个石堆，每个石堆都有一些初始大小。 一个操作选择一个源堆并将其合并到另一个源堆中。 源堆消失，目标堆增长，操作成本等于源堆的当前大小。 

不寻常的限制是在目的地一侧。 每堆最多可以收到`k`在其生命周期内传入合并。 一堆已经接受后`k`其他桩，它不能再用作目的地，尽管它仍然可以合并到另一个桩中。 

对于每个查询值`k`，我们必须计算以单堆结束所需的最小总成本。 

这些约束完全塑造了解决方案。 我们最多有`10^5`桩和`10^5`查询。 任何模拟合并中的每个查询独立的方法`O(n)`或者更糟糕的是，如果隐藏常数很大，则可能会太慢。 任何二次方都是不可能的。 我们需要预处理加上非常便宜的查询处理。 

堆垛尺寸可达`10^9`，并且总答案可能会比 32 位范围大得多。 需要 64 位整数类型。 

问题最困难的部分是了解哪种结构可以最大限度地降低成本。 粗心的贪婪很容易失败，因为限制不在于最终合并树中一个节点有多少个子节点，而在于在此过程中堆充当接收者的次数。 

一种微妙的边缘情况是`k = 1`。 

输入：```
4
1 2 3 4
1
1
```正确输出：```
20
```为什么？ 和`k = 1`，每一堆最多可以接收一次合并，因此合并过程必须形成一条链。 最小的堆首先被合并，然后合并的堆再次被合并，依此类推。 总成本变为：`1 + (1+2) + (1+2+3) = 1 + 3 + 6 = 10`但这只是增加桩的成本。 升序排序后的实际最优排序为：`1 -> 2`， 成本`1`

`3 -> (1+2)`， 成本`3`

`4 -> (...)`， 成本`6`全部的`10`。 

像霍夫曼编码那样“反复合并最小的”的天真的解释给出了`19`，在此规则下这不是最优的。 

另一个棘手的案件非常大`k`。 

输入：```
5
1 2 3 4 5
1
100
```正确输出：```
10
```一堆可以直接吸收所有其他的。 我们只需选择最大的一堆作为最终接收者，并将所有较小的一堆添加到其中。 成本是除最大堆之外的所有堆的总和。 

重复查询也很重要。 该语句允许重复`k`价值观。 每次重新计算相同的答案会浪费时间，并且可能会将原本可以接受的解决方案变成超时。 

## 方法

 一个蛮力的想法是显式模拟合并序列。 对于固定的`k`，我们可以尝试所有有效的合并订单并选择最低成本。 从概念上讲，这是可行的，因为每个操作都会以明确定义的方式更改状态。 

问题在于有效合并树的数量呈指数增长。 即使对于小`n`，搜索空间变得巨大。 子集上的动态规划大约需要`O(2^n)`状态，完全不可能`n = 10^5`。 

所以我们需要了解最佳的合并过程是什么样的。 

假设我们按升序对堆进行排序：```
a1 <= a2 <= ... <= an
```考虑一下每堆对总成本的影响有多大。 

每当一堆被合并到另一堆时，它的整个当前大小都会被再次支付。 如果一块石头在最终消失之前经历了很多关卡，那么它对答案的贡献会增加很多倍。 

这意味着小桩应该尽早消失，而大桩应该留在根部附近。 

现在看看限制。 最多可以收到一堆`k`合并。 在树语言中，每个节点最多可以有`k`孩子们。 

最优结构成为有根的`k`-ary 合并树，其中较大的值靠近根，较小的值位于较深的位置。 

排序之后，最优策略出奇的简单：

 最大的桩有深度`0`。 

下一个`k`桩有深度`1`。 

下一个`k^2`桩有深度`2`。 

下一个`k^3`桩有深度`3`。 

等等。 

如果桩有深度`d`，其价值贡献`d`倍于总成本。 所以排序后：```
answer = sum(ai * depth_i)
```其中深度是在完整的`k`从最大元素向下进行元扩展。 

为什么这是最佳的？ 因为更深的节点支付的次数更多，所以我们总是希望在最大深度处保留最小的剩余桩。 这是一个经典的交换论证。 

对于每个查询，我们可以从最小到最大处理排序数组，同时跟踪有多少元素属于每个深度层。 

由于容量呈几何级数增长，层数很少。 例如，与`k = 2`，每个深度的计数为：```
1, 2, 4, 8, ...
```所以每个查询大约运行`O(log_k n)`层转换加上数组上的线性遍历。 

当出现特殊情况时`k = 1`。 那么每一层都包含一个节点，因此深度变为：```
n-1, n-2, ..., 1, 0
```这个案例简直就是一个链条。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 |`O(n log n + q sqrt(n))`摊销|`O(n)`| 已接受 |

 ## 算法演练

 1. 按升序对堆大小进行排序。 

较小的堆应该在合并树中出现得更深，因为深度节点在成本中计算的次数更多。 
2. 预先计算排序数组的前缀和。 

这让我们可以快速计算任何连续堆块的总和。 
3. 对于每个查询`k`,特殊情况处理`k = 1`。 

当每一堆只能接收一次合并时，合并结构必须是链式的。 最小的桩有深度`n-1`，下一个有深度`n-2`， 等等。 
4. 对于`k > 1`，从最大的一堆向下逐层指定深度。 

根级别包含`1`节点。 

下一级最多包含`k`节点。 

接下来最多包含`k^2`。 

继续这种方式匹配每堆允许的最大儿童数量。 
5. 从最大到最小遍历排序后的数组。 

每当我们移动到更深的一层时，该层中的所有桩都会为答案贡献一份额外的值副本。 
6. 添加：```
depth * sum_of_values_in_this_layer
```到总答案。 
7. 输出每个查询的结果。 

### 为什么它有效

 对于合并树中位于其上方的每个祖先，一堆都会贡献一次成本。 这正是它的深度。 

限制“一堆最多可以接收`k`merges”表示合并树中的每个节点最多可以有`k`孩子们。 在所有此类树中，最小值应占据最大深度，因为较深的节点要乘以较大的系数。 

贪心层分配正是实现了这一点。 最深的可用位置由最小的剩余桩填充，这使得加权和最小化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = sorted(map(int, input().split()))

    q = int(input())
    queries = list(map(int, input().split()))

    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + a[i]

    memo = {}

    ans = []

    for k in queries:
        if k in memo:
            ans.append(memo[k])
            continue

        if k == 1:
            cur = 0
            for i in range(n):
                cur += a[i] * (n - 1 - i)

            memo[k] = cur
            ans.append(cur)
            continue

        cur = 0

        depth = 0
        cnt = 1
        r = n

        while r > 0:
            l = max(0, r - cnt)

            layer_sum = prefix[r] - prefix[l]
            cur += depth * layer_sum

            r = l
            cnt *= k
            depth += 1

        memo[k] = cur
        ans.append(cur)

    print(*ans)

solve()
```第一步对数组进行排序，因为最佳合并树将较小的值分配给较大的深度。 

前缀求和数组允许恒定时间范围求和查询。 当图层包含索引中的元素时`l`到`r-1`，其总和为：```
prefix[r] - prefix[l]
```主循环独立处理查询，但重复的查询会缓存在`memo`。 这很重要，因为该语句明确允许重复`k`价值观。 

这`k = 1`案例被分开，因为将层大小乘以`k`永远不会成长。 在这种情况下，每一层都包含一堆。 

为了`k > 1`，该算法以几何方式构建层：```
1, k, k^2, ...
```从最大的元素开始。 变量`r`标记有多少元素仍未分配。 每次迭代都取最后一个`cnt`元素并为它们分配当前深度。 

一个微妙的细节是深度从`0`在根部。 最大的一堆没有任何贡献，因为它永远不会合并到另一堆中。 

另一个容易犯的错误是其他语言中的整数溢出。 答案可能会传到身边`10^19`，因此 64 位整数是必需的。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(n log n + q sqrt(n))`摊销| 排序主导预处理，每个查询仅处理对数深度层 |
 | 空间|`O(n)`| 前缀和和记忆 |

 排序数组和前缀和均使用线性内存。 一次查询的层数非常少，因为`k`快速成长。 即使在最坏的实际情况下，该解决方案也能轻松满足以下限制：`n, q <= 10^5`。

 ## 边缘情况

 考虑尽可能最小的输入：```
1
7
1
1
```已经正好一堆了，所以不需要任何操作。 该算法自然地处理这个问题，因为根层包含深度上的唯一元素`0`，对答案没有贡献。 

现在看看限制性案例`k = 1`:```
4
1 2 3 4
1
1
```排序数组：```
[1, 2, 3, 4]
```深度作业变为：```
3, 2, 1, 0
```贡献：```
1*3 + 2*2 + 3*1 + 4*0 = 10
```该算法使用专用分支`k = 1`，避免无限的几何级数。 

对于非常大的`k`:```
5
1 2 3 4 5
1
100
```根部直接吸收其他每一堆。 

层结构：```
depth 0 -> [5]
depth 1 -> [1,2,3,4]
```回答：```
1 + 2 + 3 + 4 = 10
```一旦分配了所有元素，算法就会正确停止，即使`k^2`远大于`n`。 

最后，考虑重复查询：```
5
1 2 3 4 5
4
2 2 2 2
```如果没有记忆，相同的计算将重复四次。 该解决方案存储第一个结果并立即重用它以供以后发生。
