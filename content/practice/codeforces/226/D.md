 ## 解决方案
 ## 问题理解

 我们有一个整数矩形表$n$行和$m$列。 每个单元格包含一个数字，可以是正数、负数或零。 Harry 可以执行两种类型的运算：翻转行中所有数字的符号或翻转列中所有数字的符号。 目标是应用一系列此类操作，以便每行和每列都有非负总和。 输出应该是要翻转的行和列的集合。 

鉴于$n, m \le 100$并且每个数字的绝对值都以 100 为界，我们最多可以粗略地$10^4$如果我们执行简单的循环，则可以将解决方案保持在 2 秒的时间限制内。 尝试行和列翻转的所有组合的简单暴力方法是不可行的，因为有$2^{n+m}$可能的翻转配置，即使对于$n=m=20$。 

可能导致幼稚实现失败的边缘情况包括具有单行或单列的表，其中所有数字均为负数。 例如，如果我们有一个 4×1 表，其中包含值$[-1, -1, -1, -1]$，仅考虑孤立的行的粗心算法可能不会翻转任何内容或翻转不存在的列，而不是翻转所有行。 另一个棘手的场景是正数和负数的棋盘模式，其中翻转一行或一列会影响多个总和； 如果不收敛，天真的贪婪方法可能会无限振荡。 

## 方法

 暴力方法将尝试翻转行和列的每个子集并检查所得总和是否为非负数。 虽然保证找到解决方案（如果存在），但子集的数量为$2^{n+m}$，这显然是不可行的$n, m = 100$。 

关键的见解是，翻转行或列两次会自行取消，因此任何解决方案都可以表示为一组不重复的行翻转和一组列翻转。 此外，可以贪婪地应用翻转。 如果行总和为负，我们翻转该行使其变为正。 调整行后，我们检查列； 如果列总和为负，我们翻转该列。 然而，翻转列可能会再次使某些行总和为负，但重复应用最终会收敛，因为每次翻转都会严格增加当前负行或列的总和。 

由于数字是有界的并且网格很小，因此我们重复翻转具有负和的任何行或列的贪婪迭代方法会快速收敛并始终产生有效的配置。 最坏情况的翻转次数最多为$n + m$因为不需要将任何行或列翻转两次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(2^{n+m} \cdot n \cdot m)$|$O(n \cdot m)$| 太慢了 |
 | 贪心迭代|$O(n \cdot m \cdot (n+m))$|$O(n \cdot m)$| 已接受 |

 ## 算法演练

 1. 读取输入网格并初始化两个布尔数组以跟踪哪些行和列已被翻转。 全部初始化为 false。 
2. 计算每行的总和。 如果行总和为负，则通过将其标记为翻转来翻转该行，并取反其所有元素。 翻转行可确保行总和变为非负数。 
3. 计算每列的总和。 如果列总和为负，则通过将其标记为已翻转来翻转该列，并取反其所有元素。 翻转列可确保列总和变为非负数。 
4. 列翻转后，某些行的总和可能会变为负值。 重复步骤 2 和 3，直到没有行或列的总和为负数。 
5. 输出翻转的行和翻转的列的列表。 顺序并不重要，只要每个索引最多出现一次即可。 

为什么有效：每次翻转都会严格改善至少一个负行或列总和的符号。 一旦行或列的总和为正，进一步翻转其他行或列就不能无限地使其为负，因为每个数字都是有界的，翻转两次会自行抵消。 这保证了收敛性和正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = [list(map(int, input().split())) for _ in range(n)]

row_flip = [False] * n
col_flip = [False] * m

changed = True
while changed:
    changed = False
    for i in range(n):
        row_sum = sum(a[i][j] if not col_flip[j] else -a[i][j] for j in range(m))
        if row_sum < 0:
            row_flip[i] = not row_flip[i]
            changed = True
    for j in range(m):
        col_sum = sum(a[i][j] if not row_flip[i] else -a[i][j] for i in range(n))
        if col_sum < 0:
            col_flip[j] = not col_flip[j]
            changed = True

rows = [i + 1 for i in range(n) if row_flip[i]]
cols = [j + 1 for j in range(m) if col_flip[j]]

print(len(rows), *rows)
print(len(cols), *cols)
```该代码首先读取表并初始化两个列表以跟踪翻转。 主循环交替检查行总和和列总和。 每当发现负数时就会贪婪地应用翻转。 当没有行或列的总和为负时，循环终止。 最后，我们提取翻转的行和列的索引并打印它们。 

一个微妙的细节是我们如何计算之前翻转的总和。 如果一个单元格的行和列都没有被翻转奇数次，那么它就会做出积极的贡献。 使用带有否定的布尔值可以简化跟踪。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n * m * (n + m)) | O(n * m * (n + m)) | 每次迭代都会计算行和列的总和。 每次翻转最多触发每行或每列一次迭代。 |
 | 空间| O(n * m) | 存储表格和两个用于翻转的布尔数组。 |

 和$n, m \le 100$，最坏的情况大致是$100 * 100 * 200 = 2 \cdot 10^6$操作，在 2 秒内轻松完成。
