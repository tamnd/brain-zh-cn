 ## 解决方案
 ## 问题理解

 给定一个整数序列，我们的目标是使用最少的删除次数将其转换为“美丽”的序列。 一个漂亮的序列由连续的块组成，其中每个块都以一个指示其长度的数字开头，紧接着是那么多的元素。 例如，序列`[3, 3, 4, 5, 2, 6, 1]`已经很漂亮了，因为它可以分为`[3, 3, 4, 5]`和`[2, 6, 1]`，每个都遵守块长度规则。 

输入由多个测试用例组成。 对于每个测试用例，我们给出序列的长度`n`以及序列本身。 每个测试用例的输出是一个整数：使序列美观所需的最小删除次数。 

这些约束意味着对所有可能的子序列进行暴力破解是不可行的。`n`可以达到`2 * 10^5`，以及总和`n`所有测试用例的上限也为`2 * 10^5`，这表明`O(n log n)`或者`O(n)`每个测试用例的解决方案是可以接受的，但是`O(n^2)`会太慢。 

当序列除了删除几乎所有元素之外无法形成任何有效块时，就会出现微妙的边缘情况。 例如，`[5, 6, 3, 2]`无法形成有效的起始块，因此最小的解决方案需要删除所有内容。 在这些情况下，仅向前扫描寻找等于潜在块长度的数字的简单方法可能会失败。 

## 方法

 暴力方法尝试每一个可能的子序列并检查它是否可以分为有效的块。 对于每个起始索引，我们可以尝试读取一个长度的块`a[i]`并递归验证其余部分。 这在概念上可行，但有`O(2^n)`复杂性，这对于`n = 2 * 10^5`。 

有效解决方案的关键观察是，唯一相关的删除是那些破坏或未能完成块的删除。 如果我们将每个预期块的第一个元素视为潜在的块长度，那么问题就简化为找到与块长度结构匹配的**连续块的最长序列**。 一旦我们知道了这个序列的长度，最小的删除就是`n - total_length_of_blocks`。 

我们可以维护一个动态规划表`dp[x]`代表迄今为止看到的最长的“以 x 结尾的美丽前缀”。 然后，迭代序列，如果`a[i]`预计会持续一个长度的块`dp[a[i]]`，我们扩展它。 否则，我们开始一个新的块。 通过以这种方式更新 DP，我们可以有效地跟踪美丽子序列的最大总长度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 动态规划| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.初始化一个空字典`dp`这将映射一个整数`x`到以长度块结尾的最长美丽子序列的长度`x`。 
2. 迭代每个数字`a[i]`在序列中。 对于每个数字，检查当前值`dp`对应于预期的前一个块长度`a[i] - 1`。 如果存在这样的块，我们可以通过包含来扩展它`a[i]`。 否则，开始一个长度为1的新块。 
3. 更新`dp[a[i]]`其当前值和新计算的长度之间的最大值在此结束。 这确保我们始终为每个可能的块长度保留最长的子序列。 
4. 处理完整个序列后，得到最大值`dp`表示最长美丽子序列的长度。 
5. 所需的最少删除次数为`n - max(dp.values())`。 

**为什么有效**：该算法保持一个不变量`dp[x]`始终是以长度块结尾的最长序列的长度`x`。 每个元素要么继续现有的块，要么开始一个新的块，确保不会丢失任何有效的子序列。 因为删除被算作`n - total_length_of_blocks`，解是最小的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    dp = dict()
    for num in a:
        prev_len = dp.get(num - 1, 0)
        dp[num] = max(dp.get(num, 0), prev_len + 1)
    
    max_beautiful = max(dp.values(), default=0)
    print(n - max_beautiful)
```**解释**：我们迭代序列中的每个元素并计算以该元素结束的最长有效块链。`dp.get(num - 1, 0)`如果存在则检索前一个块的长度，如果不存在则检索 0。`max(dp.get(num, 0), prev_len + 1)`确保我们仅在增加子序列长度时才进行扩展。 处理后，用序列长度减去最长的美丽子序列即可得到答案。
