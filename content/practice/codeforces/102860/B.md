 ## 解决方案
 # 问题理解

 我们在圆的圆周上给出了几个标记点。 圆有周长`L`，每个点都用其距选定起点的顺时针距离表示。 我们需要计算三个标记点有多少种不同的选择形成一个三角形，该三角形包含圆心严格位于三角形内部或恰好位于其一侧的圆心。 

重要的几何事实是，只有当所有三个顶点都适合某个开放的半圆时，圆内切三角形的三个顶点才能包含圆心。 如果点分布超过圆的一半，则中心必须在三角形内部。 如果两个点正好相反，则中心位于三角形边界上，因此这些三角形也必须计算在内。 

输入最多可达`300000`点。 在这个尺寸下，检查每个三元组是不可能的，因为大约有`n^3 / 6`可能的三角形。 甚至`O(n^2)`当操作量太大时`n`已接近极限。 该解决方案必须按排序顺序处理点并使用线性或近线性扫描。 

棘手的情况来自开放半圆和封闭半圆之间的差异。 顶点相距正好半个圆的三角形是有效的，因为中心位于其边界上。 一个解决方案使用`<= L / 2`当搜索无效三角形时，将错误地删除这些情况。 

例如：```
3 10
0 5 6
```答案是：```
1
```点位于`0`和`5`是直径的相对两端。 三角形的中心位于连接这两个点的边上。 对待距离`5`作为坏半圆的一部分会错误地将这个三角形视为无效。 

另一种边缘情况是所有点都集中在一个小弧内。```
4 20
0 1 2 3
```答案是：```
0
```每个可能的三角形都适合一个开放的半圆，因此没有一个包含中心。 粗心的实现仅检查相邻点或仅检查圆周围的一个方向可能会错过这些情况。 

# 方法

 直接的方法是检查每一个可能的三重点。 对于每个三元组，我们可以使用几何计算中心是否在三角形内部，或者等效地检查这些点是否适合某个半圆。 这是正确的，因为考虑了每个可能的三角形，但是有`C(n,3)`三倍。 和`n = 300000`，大致就是`4.5 * 10^15`检查，这远远超出了任何实际限制。 

关键的观察结果是，计算直接包含中心的三角形比计算相反的组更难。 当一个三角形的所有顶点都位于一个空心半圆内时，该三角形是无效的。 对圆周围的点进行排序后，我们可以有效地统计那些无效的三角形。 

固定这样一个半圆的第一个点。 假设我们站在一点`i`并顺时针方向看。 如果有`k`后面的点严格小于`L / 2`离开，然后其中的每一对`k`点与点创建一个无效的三角形`i`。 这给出了`k * (k - 1) / 2`无效三角形从`i`。 

唯一剩下的问题是同一个无效三角形是否被计算多次。 对于开放半圆内的三角形，该半圆的第一个点是唯一的。 如果这三点是`a < b < c`按循环顺序和`c - a < L / 2`，然后从`b`需要环绕圆，并且环绕距离大于`L / 2`。 因此，每个无效三角形都只计算一次。 

答案是三角形总数减去无效三角形。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 太慢了 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 # 算法演练

 1. 将所有点坐标按顺时针顺序排序。 通过附加每个坐标加号来复制排序的数组`L`。 重复部分表示额外绕一圈，这使我们能够使用正常的两指针移动，而不是手动处理环绕情况。 
2.对于每个原点`i`，移动右指针直到距离`i`至少达到`L / 2`。 之间的点`i + 1`和`right - 1`正是可以加入的点`i`在一个开放的半圆内。 
3.如果有`k`这样的点，添加`k * (k - 1) / 2`到无效三角形计数。 这些都是与 结合的点对`i`创建一个不能包含中心的三角形。 
4. 计算可能的三角形总数，`n * (n - 1) * (n - 2) / 6`，并减去无效计数。 

两指针扫描背后的不变量是对于每个起点`i`，右指针始终标记在允许的开放半圆之外的第一个位置。 因为两个指针都只向前移动，所以每对点都按排序顺序被考虑一次。 计数论证证明每个无效三角形都有一个唯一的起始顶点，因此减法恰好删除了不需要的三角形。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, L = map(int, input().split())
    x = list(map(int, input().split()))
    x.sort()

    a = x + [v + L for v in x]

    bad = 0
    r = 0

    for i in range(n):
        if r < i + 1:
            r = i + 1
        while r < i + n and a[r] - a[i] < L / 2:
            r += 1
        cnt = r - i - 1
        bad += cnt * (cnt - 1) // 2

    total = n * (n - 1) * (n - 2) // 6
    print(total - bad)

if __name__ == "__main__":
    solve()
```首先对输入进行排序，因为循环顺序是半圆测试所需的唯一信息。 重复数组允许将每个搜索写为一个简单的递增间隔。 

指针`r`永远不会向后移动。 对于每个起始位置，它找到第一个不严格位于半圆内的点。 严格比较是必要的，因为点准确`L / 2`分开创建中心在边界上的有效三角形。 

价值`cnt`是之后的选择数`i`仍然可以适合同一个开放半圆。 选择其中任意两个都会给出一个无效三角形，这就是贡献为`cnt * (cnt - 1) // 2`。 

Python 整数不会溢出，因此可以安全地直接计算大量可能的三角形。

 # 边缘情况

 当两个顶点彼此相对时，必须计算三角形。 对于输入：```
3 10
0 5 6
```指针搜索自`0`之前停止`5`因为距离正好是`L / 2`。 三角形未标记为无效，总计数保持不变`1`。 

当所有点都靠近时，每个三角形都是无效的。 为了：```
4 20
0 1 2 3
```开始于`0`找到距离内的其他三个点`10`，产生三个无效三角形。 在适当的情况下，其他起点也会发生同样的情况，并且每个可能的三角形都会被删除一次。 

最常见的实施错误是使用`<= L / 2`而不是`< L / 2`。 该算法依赖于开放半圆，因为封闭半圆包括中心位于三角形边界上且必须进行计数的直径情况。
