 ## 解决方案
 ## 问题理解

 我们有一个无向公园图。 入口是顶点`1`，并且 Vasya 只能在直接连接到的顶点上完成`1`。 有效步行开始于`1`，依次使用三个不同的边，并在这些相邻顶点之一处结束。 任务是计算有多少条不同的三边游走满足这些规则。 

一次步行可以多次访问同一个顶点，但步行期间使用的三个边必须不同。 例如，序列`1 -> 2 -> 1 -> 3`无效，因为前两次移动在相反方向上使用相同的边。 

该图最多有`100000`顶点和`200000`边缘。 尝试所有可能的三边序列的解决方案是不可能的，因为行走次数可能会增长到大约平方度的总和，这远远超出了一秒限制所允许的范围。 我们需要以接近线性时间的方式处理图表。 

棘手的部分是找不到长度为三的步道。 直接计算这些很容易。 困难在于移除重复使用三个边缘之一的步道。 

一些边缘情况破坏了粗心的解决方案。 

对于只有一条边的图：```
2 1
1 2
```答案是`0`。 唯一可能的运动是`1 -> 2`，并且不能选择三个不同的边。 

对于三角形：```
3 3
1 2
2 3
3 1
```答案是`0`。 有许多三边游走在顶点旁边结束`1`，但它们中的每一个都重复一条边。 

对于明星来说：```
4 3
1 2
1 3
1 4
```答案是`0`。 任何三边运动必须立即通过已使用的边返回，因为所有道路都接触入口。 

一个常见的错误是计算每条长度为 3 的步行，其终点为`1`并忘记同一条边可能会出现两次。 

## 方法

 直接的方法会产生所有可能的步行`1 -> a -> b -> c`，检查是否`c`是一个邻居`1`，然后验证三个边是否不同。 第一个过渡有`deg(1)`选择，第二个可以有很多选择，第三个可以再次分支。 在图表的密集部分，该值变得太大。 具有高度顶点的图可以创建数十亿条候选游走。 

有用的观察结果是，计算不受限制的行走很容易，并且唯一的无效案例具有非常具体的结构。 

首先，标记顶点的每个邻居`1`。 设此集合为`S`。 

对于每个顶点`v`，计算有多少个邻居`v`属于`S`。 调用这个值`inside[v]`。 

现在考虑散步`1 -> a -> b -> c`。 第一个顶点`a`必须在`S`。 搬家后从`a`到`b`，可能的最终顶点数恰好是`inside[b]`，因为最后一个顶点必须是`1`。 对每条边求和，留下每个顶点`S`计算所有正确完成的长度为三的步行，但它也包括重复边缘步行。 

重复一条边的方法只有两种。 

前两条边可以相同。 这给出了形式的行走`1 -> a -> 1 -> c`。 有`deg(1)`选择`a`和`deg(1)`选择`c`，所以有`deg(1)^2`这样的散步。 

第二边缘和第三边缘可以相同。 这些步行的形式为`1 -> a -> b -> a`。 为每一位邻居`a`的`1`， 有`deg(a)`选择`b`，所以计数是所有邻居的度数之和`1`。 

当所有三个移动都使用相同的边时，这两种情况重叠：`1 -> a -> 1 -> a`。 正好有`deg(1)`这样的步行，所以我们将它们添加回来一次。 

最终的答案是：```
all_length_three_walks
- deg(1)^2
- sum_of_neighbor_degrees
+ deg(1)
```| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(长度-3 步数) | O(n + m) | 太慢了|
 | 最佳 | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 读取图并存储邻接表。 该图是稀疏的，因此邻接表让我们可以在线性时间内检查所有边。 
2. 查找与顶点直接相连的所有顶点`1`并标记它们。 这些是唯一可能的结束顶点，也是唯一可能的第一个顶点。 
3. 对于每个顶点，计算其邻居有多少个被标记。 该值告诉我们到达该顶点后最后一步存在多少个有效选择。 
4. 计算所有不受限制的步行。 对于每个标记的顶点`u`，检查每个边缘`u -> v`。 添加`inside[v]`因为每个标记的邻居`v`创建一个可能的终点。 
5. 减去重用第一条边的路径。 它们的结构是`1 -> u -> 1 -> v`, 给予`degree(1) * degree(1)`案例。 
6. 减去重复使用第二条边的行走。 它们的结构是`1 -> u -> v -> u`，给出所有邻居的度数总和`1`。 
7. 添加两个无效组中的回走计数。 这些正是`1 -> u -> 1 -> u`，每个邻居都有一个`1`。 

为什么它有效：

 不受限制的计数包括终止于入口旁边的所有可能的三边走道。 这种游走无效的唯一原因是它的三个边之一出现了两次。 在简单的无向图中，只有当行走立即返回到顶点时，第一条边和第二条边才能匹配`1`，并且只有当行走返回到前一个顶点时，第二条和第三条边才能匹配。 第一条边和第三条边不能相等，因为最终顶点不是入口。 由于两个无效组是单独计数的，并且它们的交集恰好是使用一条边 3 次的行走，因此包含-排除将每个无效行走恰好删除一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

g = [[] for _ in range(n)]

for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

mark = [False] * n
for v in g[0]:
    mark[v] = True

inside = [0] * n
for v in range(n):
    cnt = 0
    for u in g[v]:
        if mark[u]:
            cnt += 1
    inside[v] = cnt

total = 0
for u in g[0]:
    for v in g[u]:
        total += inside[v]

deg1 = len(g[0])

bad_first_two = deg1 * deg1

bad_second_three = 0
for u in g[0]:
    bad_second_three += len(g[u])

answer = total - bad_first_two - bad_second_three + deg1

print(answer)
```数组`mark`表示可能的结束顶点。 这`inside`array 避免在计算行走时重复扫描顶点的邻居。 

变量`total`遵循算法中描述的无限制步行计数。 它故意忽略边缘重复，因为这些情况有一个简单的公式，并且随后减去的成本更便宜。 

修正项仅使用整数运算。 Python 整数不会溢出，这很有用，因为游走的数量可能远大于边的数量。 

该图内部是零索引的，因此入口顶点存储为索引`0`。 不需要特殊的边界处理，因为邻接列表自然只包含现有的顶点。

import sys
import io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, m = map(int, input().split())
    g = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    mark = [False] * n
    for v in g[0]:
        mark[v] = True

    inside = [0] * n
    for v in range(n):
        for u in g[v]:
            if mark[u]:
                inside[v] += 1

    total = 0
    for u in g[0]:
        for v in g[u]:
            total += inside[v]

    d = len(g[0])
    bad = d * d
    for u in g[0]:
        bad += len(g[u])

    return str(total - bad + d)

 ## 边缘情况

 对于单边图：```
2 1
1 2
```标记集仅包含顶点`2`。 无限制计数为零，因为没有足够的边来形成三步行走。 修正项也保持为零，给出正确的结果。 

对于三角形：```
3 3
1 2
2 3
3 1
```无限制计数发现六种可能的游走。 四个重复使用第一条边，四个重复使用最后两条边缘，两个都计入两组。 公式给出`6 - 4 - 4 + 2 = 0`。 

对于星图：```
4 3
1 2
1 3
1 4
```每次离开入口的运动都必须立即使用同一边缘返回，因为不存在其他道路。 无效行走校正完全消除了不受限制的计数。 

该算法可以处理这些情况，因为它将简单的计数问题与步行可能失败的确切结构原因分开。
