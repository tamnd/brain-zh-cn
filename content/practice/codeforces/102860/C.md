 # 问题理解

 游戏由独立回合组成。 每轮开始时，得分变为`n`。 每个生成器值代表一次移动：Petya 尝试从当前分数中减去该值，但仅应用成功的减法。 当分数正好为零时，当前回合完成，下一步（如果存在）从新分数开始`n`。 

输入给出了移动次数、一轮的初始分数以及生成器输出的整个序列。 任务是重播这些动作并确定完全完成了多少轮以及最终记录的动作后剩余的分数。 如果最后一步完成一轮，之后就没有开始新的一轮，所以最终得分为零。 

这些限制足够小，足以进行直接模拟。 最多有`100000`移动，因此处理每个移动一次的算法仅执行大约`100000`运营。 任何尝试构建所有可能的轮划分或重复扫描序列的方法都会增加不必要的工作，但线性时间很容易在限制之内。 

主要的边缘情况来自正确处理失败的减法和一轮结束的确切时刻。 例如，使用输入```
1 5
7
```输出是```
0
5
```因为`7`不能从中减去`5`，所以分数保持不变。 总是减去生成器值的粗心解决方案会产生无效的负分数。 

另一种情况是```
1 5
5
```带输出```
1
0
```因为唯一的一步就完成了这一轮。 一个常见的错误是将分数重置为`5`达到零后立即进行，这会错误地将最终分数报告为新一轮的起始分数。 

第三种边界情况是```
3 5
2 2 2
```带输出```
0
1
```移动将分数改变为`5 -> 3 -> 1 -> 1`，因为最后的减法是不可能的。 将每个生成器值计算为完成一轮的进度的解决方案会过度计数。 

## 方法

 最直接的解决办法就是精确模拟游戏。 我们保留当前得分和已完成的回合数。 对于每个生成器值，我们检查减去它是否使分数保持非负数。 如果是，我们应用减法。 当分数变为零时，一轮就结束了，所以我们增加答案并为下一步准备分数。 

暴力解释实际上与这里的最佳方法相同。 没有隐藏的需要更快的数学捷径，因为游戏状态仅在每次移动后改变，并且移动次数是有限的。 尝试将序列的每一个可能的分区分成几轮的假设方法将探索大量的可能性，但模拟通过遵循唯一有效的事件顺序来完全避免这种情况。 

解锁解决方案的观察结果是生成器序列已经是游戏的完整历史。 没有选择可以做。 下一个状态仅取决于当前分数和下一个生成器值，因此一次遍历序列就足够了。

 ## 算法演练

 1. 将当前分数初始化为`n`并将已完成的回合计数器归零。 分数代表 Petya 在处理第一个记录的移动之前的状态。 
2. 按照每个生成器值出现的顺序处理它。 如果该值不大于当前分数，则从分数中减去该值。 否则，请忽略它，因为规则不允许分数变为负数。 
3、每次减法成功后，检查分数是否归零。 如果是，则增加已完成回合计数器并将分数恢复为`n`以便将来的行动。 恢复代表下一轮的开始，但如果当前移动是最后一步，则不会影响最终答案，因为这种情况下所需的最终分数为零。 
4. 处理完所有动作后，打印已完成的轮数和当前得分。 如果最后一步结束了一轮，则在最后一步之后不应发生恢复步骤，因此最终得分保持为零。 

实施中需要对最后一步进行一个小的调整。 我们可以在一轮结束时立即恢复分数，因为循环后我们只需要游戏停止那一刻的分数。 为了保留该信息，代码会在重置之前检查当前移动是否是最终移动。 

工作原理：在模拟过程中，存储的分数始终是 Petya 在处理所有动作后的准确分数。 当游戏规则允许时，精确地应用移动，并且当分数达到零时，精确地计算完成的回合。 由于每个记录的移动都会按照原始顺序处理一次，因此最终存储的状态与真实的游戏状态相匹配。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    k, n = map(int, input().split())
    a = list(map(int, input().split()))

    score = n
    rounds = 0

    for i, x in enumerate(a):
        if x <= score:
            score -= x

        if score == 0:
            rounds += 1
            if i != k - 1:
                score = n

    print(rounds)
    print(score)

if __name__ == "__main__":
    solve()
```变量`score`和`rounds`直接表示输出中请求的两个数量。 该循环从左到右遵循生成器历史记录，与游戏顺序相匹配。 

减法条件使用`x <= score`而不是在减法之后进行检查，因为 Python 整数允许负值，但游戏本身不允许。 这可以防止无效的中间状态。 

重置条件检查当前移动是否是最终移动。 如果一轮较早结束，则下一个记录的着法属于新一轮，并且必须从`n`。 如果最后一步结束了一轮，则不会开始新一轮，因此答案必须将分数保持为零。 

不存在索引技巧或大整数问题。 这些值很容易适合 Python 的整数类型，并且该算法仅存储输入序列和一些变量。

 ## 边缘情况

 对于本案```
1 5
7
```该算法从五分开始。 唯一的生成器值大于分数，因此不会发生减法。 分数永远不会为零，回合计数器仍为零，最终分数为五。 

对于本案```
1 5
5
```减法成功并将分数从 5 更改为 0。 该算法计算一个已完成的回合。 由于这是最后一步，因此不会重置分数，将所需的最终分数保留为零。 

对于本案```
3 5
2 2 2
```第一步将分数更改为 3，第二步将分数更改为 1。 第三步不能应用，因为二比一大，所以分数仍然是一。 该算法从不计算一轮，因为永远不会达到零。 

对于本案```
5 4
3 1 5 4 2
```前两个动作完成一轮。 第三步从四分开始，失败，分数保持不变。 第四步完成第二轮。 最后一步从四开始，剩下二。 该算法正确处理中间重置和最终非零分数。
