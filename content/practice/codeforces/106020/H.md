 ## 解决方案
 ## 问题理解

 我们得到一个非负整数数组。 对于数组的每个连续段，我们可以计算两个值。 第一个是段内所有元素的总和。 第二个是段的MEX，它是其中没有出现的最小非负整数。 任务是计算有多少段这两个值相等。 

数组长度可以达到$10^5$。 检查每个可能的子数组的直接方法将考虑$n(n+1)/2$段，大致是$5 \cdot 10^9$在最大的情况下。 即使检查一个段的时间是恒定的，这也远远超出了一秒解决方案的处理能力。 我们需要避免枚举所有子数组。 

元素取值范围较大也是一个暗示。 实际值并不重要，重要的是它们与 MEX 的关系。 由于所有数字都是非负数，因此当子数组包含较大值时，子数组的总和会快速增长。 这让我们证明只有非常小的 MEX 值才能起作用。 

第一个边缘情况是 MEX 等于 0 的段。 例如：```
Input:
3
5 5 5
```整个数组的总和为 15，而不是 0，但每个子数组的 MEX 为 0，因为任何地方都没有零。 正确答案是 6，而不是 0。仅查找包含零的子数组的解决方案将错过所有子数组。 

第二种边缘情况是当段包含超大值时。 例如：```
Input:
4
0 1 100 2
```子数组`[0,1,100,2]`有 MEX 3，但其总和为 103，因此无效。 如果粗心地只检查从 0 到 MEX-1 的所有数字是否都出现，可能会计算错误。 

第三个边缘情况是关于重复的。 例如：```
Input:
4
0 1 2 2
```子数组`[0,1,2,2]`有 MEX 3，但总和为 5。有效的 MEX 3 段必须恰好包含值 0、1 和 2，且不包含任何其他正值。 

## 方法

 一个自然的暴力解决方案是修复左端点并扩展右端点。 在扩展时，我们使用值的频率来维护当前总和和当前 MEX。 这是正确的，因为每个子数组都被访问一次，我们可以立即测试条件。 

问题是子数组的数量。 有$O(n^2)$其中，所以最坏的情况表现约为$5 \cdot 10^9$扩展。 这太慢了。 

关键的观察结果来自于与 MEX 的总和的比较。 假设子数组的 MEX 等于$m$。 那么它必须包含从 0 到$m-1$，因此子数组的最小可能和为：$$0+1+2+\dots+(m-1)=\frac{m(m-1)}{2}$$为了这个等于$m$，我们需要：$$\frac{m(m-1)}{2} \le m$$这仅适用于$m \le 3$。 因此每个有效子数组都有 MEX 0、1、2 或 3。 

现在每个案例都变得简单了。 MEX 为 0 表示子数组不包含零。 MEX 为 1 意味着它恰好是一个零。 MEX 为 2 意味着它必须包含 0 和 1 而没有其他内容，因此它的长度为 2。 MEX 为 3 意味着它必须恰好包含值 0、1 和 2，因此它的长度为 3。 

整个问题简化为检查尺寸非常小的窗口。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算所有 MEX 等于 0 的子数组。这些正是不包含零的连续块。 如果一个块有长度$k$，它贡献$k(k+1)/2$子数组。 
2. 计算所有 MEX 等于 1 的子数组。该段必须包含 0，不能包含 1。 由于其总和必须为 1 并且所有值均为非负数，因此唯一可能的段是`[0]`。 每一个零加一。 
3. 计算所有 MEX 等于 2 的子数组。该段必须同时包含 0 和 1。它们的总和已经为 1，因此该段正好还需要 1 个单位。 唯一的可能性是相邻的一对`[0,1]`或者`[1,0]`。 
4. 计算所有 MEX 等于 3 的子数组。该段必须包含 0、1 和 2。它们的总和已经为 3，因此该段不能包含其他任何内容。 该段的长度必须为三，并且其值必须恰好是这三个数字。 
5. 将四个计数相加。 这些情况涵盖了每个可能的有效子数组，因为没有更大的 MEX 可以满足求和条件。 

为什么它有效：每个有效的子数组都有一个 MEX 值。 上面导出的不等式证明 MEX 不能超过 3。对于每个可能的 MEX，所需的总和强制采用非常特定的结构。 该算法精确地计算这些结构，因此每个计算的子数组都是有效的，并且每个有效的子数组都被计算在内。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    ans = 0

    # MEX = 0
    length = 0
    for x in a:
        if x == 0:
            ans += length * (length + 1) // 2
            length = 0
        else:
            length += 1
    ans += length * (length + 1) // 2

    # MEX = 1
    for x in a:
        if x == 0:
            ans += 1

    # MEX = 2
    for i in range(n - 1):
        if (a[i] == 0 and a[i + 1] == 1) or (a[i] == 1 and a[i + 1] == 0):
            ans += 1

    # MEX = 3
    for i in range(n - 2):
        if a[i] + a[i + 1] + a[i + 2] == 3:
            if a[i] != a[i + 1] and a[i] != a[i + 2] and a[i + 1] != a[i + 2]:
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```第一个循环通过在每个零处分割数组来处理 MEX 0。 变量`length`存储当前的纯正块大小。 当块结束时，它的贡献是其中可能的子数组的数量。 

第二个循环处理 MEX 1。单个零是唯一有效的段，因为任何其他值都会使总和大于 MEX。 

第三个循环检查相邻对。 唯一长度和为 2 且 MEX 2 的两个段是`[0,1]`和`[1,0]`。 

最后的循环检查三个窗口的长度。 总和必须正好为 3，并且三个值必须不同。 因为唯一可能的值是 0、1 和 2，所以 MEX 恰好是 3。 

没有前缀和或映射，因为结构观察减少了对恒定大小窗口的所有可能答案。

import sys
import io

def solve(inp):
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    ans = 0

    length = 0
    for x in a:
        if x == 0:
            ans += length * (length + 1) // 2
            length = 0
        else:
            length += 1
    ans += length * (length + 1) // 2

    for x in a:
        if x == 0:
            ans += 1

    for i in range(n - 1):
        if (a[i], a[i + 1]) in [(0, 1), (1, 0)]:
            ans += 1

    for i in range(n - 2):
        if sorted(a[i:i+3]) == [0, 1, 2]:
            ans += 1

    return str(ans) + "\n"

assert solve("1\n0\n") == "1\n"

assert solve("5\n0 1 2 5 6\n") == "4\n"

assert solve("4\n5 5 5 5\n") == "10\n"

assert solve("6\n0 1 2 0 1 2\n") == "4\n"

 ## 边缘情况

 对于全阳性的情况：```
4
5 5 5 5
```每个子数组都有 MEX 0，因为缺少零。 该算法永远不会进入 MEX 1、2 或 3 情况，但正块计数会增加$4 \cdot 5 / 2 = 10$，这正是子数组的数量。 

对于几乎满足 MEX 3 的段：```
4
0 1 2 2
```窗户`[0,1,2]`被计数是因为它有 sum 3 和 MEX 3。窗口`[0,1,2,2]`被忽略，因为长度不是 3 并且附加 2 增加了总和。 固定大小的窗口检查自然可以防止这种错误。 

对于大于可能的 MEX 的值：```
4
0 1 100 2
```唯一可能的有效段是`[0]`和`[0,1]`如果相邻，但值 100 不能参与有效的 MEX 3 段。 该算法从不特殊对待大值，因为早期的证明已经保证它们不会出现在有效的较高 MEX 段中。
