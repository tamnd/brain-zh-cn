 ## 解决方案
 ## 问题理解

 我们有一棵无向树$n$顶点。 任务是为每个顶点分配三个标签之一，$a$,$b$， 或者$c$，这样就没有边连接具有相同标签的两个顶点。 在所有此类有效分配中，我们被要求生成按字典顺序连接的最小字符串，该字符串是通过按以下顺序连接顶点标签而形成的：$1$到$n$。 

树结构仅通过邻接约束起作用。 要求纯粹是边缘本地的，但目标是全局的，因为字典顺序取决于整个字符串。 这种结合迫使我们在意识到未来冲突的情况下贪婪地选择标签。 

约束允许最多$2 \cdot 10^5$顶点，这排除了所有标签的任何指数回溯或逐顶点强力检查。 即使在不修剪的情况下尝试每个节点的三个选择也会导致$3^n$，这是完全不可行的。 任何有效的解决方案都必须在线性或近线性时间内运行，本质上$O(n)$或者$O(n \log n)$。 

当在不考虑树结构的情况下使用朴素的贪婪策略时，就会出现微妙的失败模式。 例如，始终在本地分配尽可能小的标签而不考虑父约束可能会在以后陷入困境。 

考虑一条简单的路径$1 - 2 - 3$。 如果我们分配$s_1 = a$，然后贪婪地赋值$s_2 = a$由于它是局部最小的，我们立即违反约束，但即使我们在局部强制执行有效性，选择$s_2 = b$进而$s_3 = a$给出“aba”，这是正确的。 然而，在像星形这样的分支结构中，根为 1，邻居为 2、3、4，如果独立处理，粗心的方法可能会将所有子级贪婪地分配为“a”，从而产生无效的输出，例如“aaa？” 这违反了每个边缘的约束。 

另一个微妙的问题来自遍历顺序。 如果我们按 DFS 顺序处理节点而不修复父级优先的依赖关系，则在某些不正确的实现中，我们可能会在知道其父级的最终标签之前分配一个子级。 这会导致决策不一致和结果无效。 

## 方法

 蛮力的想法是生成所有的分配$\{a,b,c\}$到$n$顶点并仅保留那些满足边缘约束的顶点。 对于每个有效的分配，我们计算它的字典值并保留最小值。 

这是有效的，因为它明确地检查了每个可能的标签，但在规模方面它立即失败了。 作业数量为$3^n$，以及每次验证成本$O(n)$检查所有边缘，给出$O(n \cdot 3^n)$，甚至变得无法使用$n = 20$，更不用说$2 \cdot 10^5$。 

关键的结构观察是树木是二分的，但有一种额外的颜色可用。 如果我们仅限于两种颜色，则解决方案将被固定为交换。 通过三种颜色，我们获得了灵活性：在每个节点，我们只需要避开父节点的标签，结构的其余部分除了邻接之外不施加任何额外的直接约束。 

这表明了贪婪的构造。 如果我们将树建立在任何地方，则节点的唯一约束是其父节点和 DFS 中已分配的邻居。 由于在前序遍历中处理节点时还没有分配子节点，因此我们只需要避开父节点的颜色即可。 这将每个决策最多减少为两个有效选择。 在每个步骤中选择最小的有效标签可以保证词典编排的最小性，因为较早的位置主导排序。 

正确性取决于这样一个事实：一旦分配了节点，就不需要重新考虑。 树结构保证没有循环，因此不存在向后约束传播。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n \cdot 3^n)$|$O(n)$| 太慢了 |
 | 贪婪 DFS 着色 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们以顶点 1 为树根。目标是以尊重父子约束的方式分配标签，同时始终优先选择尽可能小的标签。 

1. 选择任意根（通常为顶点 1），并构建树的邻接表表示。 这允许高效的遍历而无需重新计算邻居。 
2. 从根启动 DFS。 为根分配最小的标签，该标签始终是$a$。 这种选择是安全的，因为不存在与之冲突的祖先，并且它最小化了结果字符串的第一个字符。 
3. 对于每个节点$v$，在处理其子级时，根据其父级标签独立决定每个子级的标签。 由于约束只是相邻节点不同，因此子节点必须避开父节点的标签。 
4. 分配尽可能小的标签$\{a, b, c\}$这不等于父母的标签。 这种贪心选择是有效的，因为它只影响字符串中的当前位置； 后面的作业不会影响前面的词典顺序。 
5. 继续递归进行 DFS，将所选标签作为更深节点的父约束传递。 

它起作用的原因来自于树的结构和字典顺序的本质。 每个节点的标签仅影响其在最终字符串中的位置，并且不会限制超出共享父约束的兄弟节点。 由于我们总是在每个位置选择最小的可用标签，因此以后的校正无法在不违反该节点的边缘约束的情况下产生字典顺序更小的前缀。 由于依赖图是非循环的，因此分配是局部最优且全局一致的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    res = [''] * (n + 1)

    def dfs(u, parent):
        for c in "abc":
            if c != res[parent]:
                res[u] = c
                break
        for v in g[u]:
            if v != parent:
                dfs(v, u)

    res[0] = '#'  # dummy parent so root can take 'a'
    res[1] = 'a'
    for v in g[1]:
        dfs(v, 1)

    return "".join(res[1:])

print(solve())
```该实现依赖于简单的 DFS 遍历。 根单独初始化以确保它采用最小的标签。 虚拟值用于其父级，以便根不受约束。 

主要的微妙之处是确保我们永远不会与未初始化的父标签进行比较。 使用`res[parent]`直接工作，因为每个节点在处理其子节点之前就已分配。 

另一点是递归深度。 由于树可以是长链，Python默认的递归限制不够，所以增加了。

 ## 边缘情况

 单个顶点树是最简单的场景。 该算法立即分配根“a”，并且不会发生进一步的遍历。 由于没有边，所以这是非常有效的。 

二节点树测试父约束是否得到正确执行。 根得到“a”，孩子必须得到“b”。 任何将“a”分配给子级的尝试都会违反边缘规则，因此这会检查过滤逻辑的正确性。 

星形树测试兄弟独立性是否得到正确处理。 每个子项都单独处理，但都必须避开根的标签。 该算法将它们全部分配为“b”，这仍然有效，因为兄弟姐妹不受直接约束。 

深链测试 DFS 是否正确地通过多个级别传播约束。 每个节点仅依赖于其父节点，并且交替分配自然出现，无需额外的簿记。
