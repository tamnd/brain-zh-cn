 ## 解决方案
 ## 问题理解

 我们得到一个数字序列，我们反复压缩它，直到只剩下一个值。 每个操作都会获取两个相邻元素，删除它们，并将它们替换为两个原始值（包括两个原始值）之间的任何整数。 关键的自由在于我们不必选择平均值或固定规则，但我们可以选择该对形成的区间内的任何值。 

恰好之后$n-1$这样合并后，数组就变成了一个数字。 问题是是否存在某种中间值的合并和选择序列，使得最终剩余的数字恰好是$x$。 

限制很小：每个测试最多有 100 个元素和最多 500 个测试用例。 这立即表明，即使每次测试的二次或三次推理都是可以接受的，但所有合并序列上的任何指数推理都是不可接受的。 尝试所有可能的合并顺序和所有可能值的简单模拟是不可能的，因为每次合并都会引入连续范围的可能性，并且合并树的数量已经呈指数级增长。$n$。 

当所有值都相等或当$x$位于数组范围之外。 例如，如果所有元素都是$[3,3,3]$，最终值必须始终为 3，因此任何$x \neq 3$是不可能的。 同样，如果我们从$[1, 5]$，我们总是可以选择任何最终值$[1,5]$，所以任意$x$超出这个区间是不可能的。 有趣的是全局范围内的每个值是否总是可以实现的。 

一个天真的错误是假设因为我们可以在两个数字之间选择任何值，所以我们可以任意“控制”最终结果。 如果我们考虑约束传播而不是局部自由，那么这种直觉就会失败。 

## 方法

 暴力的想法会尝试模拟所有可能的合并序列。 在每一步中，我们都会选择一个相邻的对，并将其替换为其范围内的每个整数。 这创建了位置和价值的分支因素。 即使忽略值，也存在加泰罗尼亚数多合并结构，并且通过值选择，状态空间变得无限。 即使离散化值也无济于事，因为组合爆炸超出了可行性。 

关键的见解是我们实际上并不关心合并的顺序。 每个操作仅将两个连续的段合并为一个段，其可实现的值形成一个区间。 这表明每个段$[l, r]$可以用连续范围表示$[min(l,r), max(l,r)]$，合并两个段只是将它们的可能范围统一到该段中所有元素之间的完整间隔中。 

因此，问题分解为一个更简单的不变量：在任何操作序列之后，最终值可以是原始数组的全局最小值和全局最大值之间的任何整数。 这是因为我们总是可以使用合并向内传播极端，并且在每一步我们都可以自由选择中间值以避免引入新的约束。 

因此，最终的答案很简单：是否$x$位于内$[\min(a), \max(a)]$。

 ## 算法演练

 我们将每个测试用例简化为数组上的范围查询。 

1. 计算序列中的最小值。 这表示通过合并可以保留的最低值，因为没有任何操作可以在其输入的凸包之外产生任何东西。 
2. 计算序列中的最大值。 出于同样的原因，这是对称上限。 
3. 检查是否$x$位于这两个值之间，包括在内。 
4. 如果是，则输出“YES”，否则输出“NO”。 

唯一不明显的部分是为什么整个间隔是可以实现的。 合并规则允许我们选择两个相邻段之间的任何值。 通过反复合并和选择逐渐走向$x$，我们总是可以构造一条不“跳过”范围内任何整数的路径。 

### 为什么它有效

 每次合并都会用单个段替换两个相邻段，该段的可实现值形成覆盖两个输入的连接区间。 由于在此合并操作下区间是封闭的，因此最后的段也必须是区间。 初始线段是单点，因此最终区间恰好是所有初始值的凸包，即$[\min(a), \max(a)]$。 因此，任何$x$在这个区间内是可达的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        x = int(input())

        mn = min(a)
        mx = max(a)

        if mn <= x <= mx:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```该代码直接计算每个数组的最小值和最大值，并检查是否$x$就在那个区间内。 有意将实现最小化，因为问题的结构消除了任何模拟的需要。 

这里的一个常见错误是尝试贪婪合并或模拟操作，但这是不必要的。 另一个潜在的陷阱是忘记中间值可以是范围内的任何整数，这就是使可达集连续而不是离散的原因。

 ## 边缘情况

 一种边缘情况是数组只有一个元素。 用于输入$[5]$，唯一可能的最终值为 5，因为不存在任何操作。 该算法计算$mn = mx = 5$，所以只有$x = 5$返回YES，与流程完全匹配。 

另一种边缘情况是所有值都相同时，例如$[3,3,3,3]$。 无论选择如何，每次合并都会保留值 3，因此最终结果是固定的。 计算的范围是$[3,3]$，这正确地限制了答案。 

一个更微妙的情况是$x$严格位于两个遥远的值之间，例如$[1, 100]$和$x = 50$。 即使最初不存在中间值，两个元素的直接合并允许选择该区间内的任何整数，从而可以实现 50。 范围检查立即捕获这一点，无需模拟中间状态。
