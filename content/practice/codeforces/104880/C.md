 ## 解决方案
 ## 问题理解

 我们得到一个由小写字母组成的字符串。 任务是计算我们可以按升序选择四个位置的方式有多少种，以便这些位置上的字符形成模式`c`， 然后`v`， 然后`b`， 然后`b`。 

换句话说，我们正在计算长度为四等于固定模式“cvbb”的子序列，其中我们可以跳过字符但必须保持顺序。 

输入大小最多可达 100,000 个字符。 尝试枚举所有四元组的直接组合方法立即不可行，因为索引四元组的数量约为$\binom{n}{4}$，这大约是$10^{20}$在最坏的情况下。 在一秒的限制下，即使检查每个四元组也是不可能的。 

因此，解决方案必须使用前缀信息在线性或近线性时间内处理字符串，以便我们永远不会显式枚举子序列。 

一些边缘情况值得明确。 

如果字符串包含的内容少于 1`c`，答案为零。 例如，`vvbbbbb`显然无法形成图案。 

如果有多个`b`一旦我们到达最后一个阶段，角色、组合就会迅速爆炸，因此不仔细分开位置的幼稚计数将会多算。 例如，在`c v b b`，确实有一个有效的子序列，但是粗心的计数相乘`b`不尊重顺序的对将计算无效组合。 

重复的字母是主要的微妙之处：我们必须确保索引严格递增，因此我们不能将出现的事件视为没有顺序约束的独立选择。 

## 方法

 蛮力的想法很简单：尝试每个索引的四元组$i < j < k < l$,检查字符是否匹配`c v b b`，并计算有效的。 这是正确的，因为它明确强制执行子序列的定义。 

然而，四倍数的数量随着$O(n^4)$。 和$n = 10^5$，这是关于$10^{20}$迭代次数，这远远超出了任何可行的限制。 

关键的观察结果是该模式是固定且短的。 我们可以从左到右逐步构建答案，而不是全局选择索引。 在每个位置，我们只关心可以扩展多少个长度为 1、2 和 3 的有效部分子序列。 

我们跟踪与目标模式的前缀匹配的部分子序列的计数：

 - 有多少个子序列相等`c`- 有多少个相等`cv`- 有多少个相等`cvb`- 有多少个相等`cvbb`当我们扫描一个新字符时，我们以反向依赖顺序更新这些计数器，以便每个阶段仅依赖于较早的阶段。 

这将问题简化为单次传递，每个角色的工作量不断增加。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^4) | O(n^4) | O(1) | O(1) | 太慢了 |
 | 最佳 DP 计数 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从左到右处理字符串并维护四个计数器。 

让：

-`c1`= 子序列数等于`c`-`c2`= 子序列数等于`cv`-`c3`= 子序列数等于`cvb`-`c4`= 子序列数等于`cvbb`我们根据当前角色更新这些计数器。 

1.初始化所有计数器`c1, c2, c3, c4`为零。 
2. 迭代每个字符`x`在字符串中从左到右。 
3.如果`x == 'c'`，我们可以开始一个长度为1的新子序列。`c1`by 1. 这表示选择这个位置作为未来模式的第一个字符。 
4. 如果`x == 'v'`，每一个现有的`c1`子序列可以扩展为`cv`使用该位置作为子序列`v`。 添加`c1`到`c2`。 
5. 如果`x == 'b'`，我们更新两个阶段：

 - 每个现有的`c2`可以扩展到`cvb`，所以添加`c2`到`c3`。 
- 每个现有的`c3`可以扩展到`cvbb`，所以添加`c3`到`c4`。 

从概念上讲，顺序很重要：两次更新都必须使用处理此字符之前的值。 
6.处理完所有字符后，`c4`包含子序列的数量等于`cvbb`。 

为什么这种顺序是正确的，因为每个字符要么开始一个新的子序列，要么扩展先前形成的子序列而不重复使用相同的位置。 

### 为什么它有效

 在扫描中的任何点，每个计数器都表示选择以前缀某处结尾且与模式的相应前缀匹配的递增索引子序列的方法数。 当我们处理一个新字符时，我们只扩展严格在当前位置之前结束的子序列，因此顺序会自动保留。 因为每个有效的子序列都由选择每个字符的最后一个位置唯一标识，所以每个结构都只计算一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    c1 = c2 = c3 = c4 = 0

    for ch in s:
        if ch == 'c':
            c1 += 1
        elif ch == 'v':
            c2 += c1
        elif ch == 'b':
            c4 += c3
            c3 += c2

    print(c4)

if __name__ == "__main__":
    solve()
```该实现使四个累加器与部分模式匹配完全对应。 里面的更新顺序`'b'`情况危急。 我们先推`c3`进入`c4`因为两者都依赖于之前的状态，然后更新`c3`使用`c2`。 如果反转，则新创建`c3`值会错误地贡献于`c4`在同一次迭代中。 

所有算术都是用 Python 整数完成的，它可以安全地处理大量计数，因为子序列的数量可以超过 64 位限制。

 ## 边缘情况

 一个重要的情况是当有很多`b`有效后的字符`cv`子序列。 用于输入`cvbbbb`，我们正好有一个`c`和一个`v`， 所以`c2 = 1`当我们到达`b`s。 每个`b`首先增加`c3`从 0 到 1, 2, 3, 4 跨越四个位置，然后每个新`c3`有助于`c4`。 该算法正确地累积了这个值，因为每个`b`两者都扩展了现有的`cvb`子序列并有助于未来的扩展。 

另一个案例又重复了`c`任何之前的字符`v`。 为了`cccvbb`， 这`c1`计数器变为3，意味着存在三个独立的起点。 当第一个`v`出现，`c2`变为3，保留了选择的多样性。 这表明该算法自然地编码组合分支，而无需显式存储位置。 

最后一个微妙的情况是交错，例如`cvcvb b`。 该排序确保每个扩展仅使用前缀，因此即使字符交错，也不会发生索引的无效重用。 每次更新仅依赖于较早的计数器，保留严格的递增索引约束。
