 ## 解决方案
 ## 问题理解

 我们正在与一个隐藏的长度数组进行交互$n$，其中每个位置代表一件衣服并存储来自$1$到$n$。 我们的目标是恢复整个隐藏的类似排列的配置，但不保证它是排列，因为允许重复。 

我们可以执行的唯一操作是提交长度为完整的猜测数组$n$。 每次猜测后，系统都会回复有多少个位置完全正确，即有多少个索引$i$满足$a_i = b_i$， 在哪里$b$是隐藏数组。 如果所有位置都正确，我们立即完成。 否则我们继续，最多严格限制$10n$查询。 

因此，该任务是一个反馈极弱的交互式重建问题：只有全局汉明相似度得分。 

限制因素$n \le 500$和查询限制$10n$强烈表明任何需要对所有值进行每个位置强力的方法都处于边缘，但仍然合理。 一个直接的幼稚策略是$O(n^2)$猜测或更糟的是，如果结构不仔细，可能会超出查询预算。 

如果我们在没有协调的情况下尝试独立的每个位置猜测，就会出现微妙的失败情况。 例如，如果我们固定除一个之外的所有位置，并在所有值中循环该位置，我们可能需要$n$每个索引的查询总数$n^2$，这违反了限制$n = 500$。 

关键的挑战是反馈是聚合的，因此简单的坐标隔离成本太高。 

## 方法

 蛮力思维会尝试独立确定每个位置。 对于固定索引$i$，我们可以保持所有其他位置不变并尝试所有$n$位置可能的颜色$i$。 每当分数增加一时，我们就找到了该位置的正确值。 

这是正确的，因为分数差异隔离了单个坐标的正确性。 然而，这种方法的成本$n$每个位置的查询，导致$n^2$总查询数。 为了$n = 500$， 这是$250{,}000$查询，远远超出允许的范围$5000$。 

改进来自于我们注意到我们不需要一一隔离仓位。 每个查询都会提供全局对齐信息，我们可以将问题视为重复改进完整的候选数组，而不是单独修复坐标。 我们不是扫描每个位置的值，而是保持当前的猜测，并且只有在有证据表明更改可以提高正确性时才对其进行修改。 

关键思想是汉明相似性上的贪婪爬山：每当我们怀疑坐标错误时，我们都会尝试用不同的值替换它，并且仅在分数提高时才保留更改。 由于每次改进都会严格增加正确位置的数量，并且分数受以下限制$n$，我们最多只能接受$n$整体改进，使流程在内部高效$10n$查询。 

这将问题从坐标搜索转换为全局增量优化。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个位置的强力 |$O(n^2)$查询 |$O(n)$| 太慢了|
 | 通过全局反馈进行贪婪改进 |$O(n)$查询 |$O(n)$| 已接受 |

 ## 算法演练

 我们维护一个任意初始化的当前猜测数组，例如全部初始化。 我们还保持其针对隐藏数组的当前分数。 

1.初始化猜测数组，将所有位置设置为1，然后查询它以获得初始分数。 这给出了没有任何假设结构的基线对齐。 
2. 对于每个位置$i$，我们尝试确定其当前值是否正确。 我们暂时只修改$a_i$，循环遍历可能的值$1$到$n$。 
3. 对于位置处的每个试验值$i$，我们发出完整的查询。 如果返回的分数与当前最佳分数相比有所增加，我们接受该值并永久更新数组。 增加保证了这个立场现在是正确的或者我们已经更接近正确了。 
4. 如果没有变化会提高位置得分$i$，我们恢复它之前的值。 这确保我们永远不会降低当前解决方案的性能。 
5. 我们对所有索引继续此过程，重复细化数组直到查询返回$n$，意味着完全正确。 

关键的设计选择是，我们只进行严格提高全局分数的更改，这可以防止振荡并保证稳定的进展。 

### 为什么它有效

 每个接受的修改都会将正确位置的数量增加一，因为更改单个索引只能影响该索引在匹配隐藏数组方面的正确性。 由于分数的上限为$n$，我们最多可以接受$n$改进。 每个不提高分数的查询都会被丢弃，因此浪费的查询也受到每个位置的限制。 这可确保查询总数保持在线性预算范围内。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(arr):
    print(*arr)
    sys.stdout.flush()
    x = int(input())
    if x == -1:
        sys.exit(0)
    return x

def solve():
    n = int(input())

    cur = [1] * n
    cur_score = ask(cur)

    for i in range(n):
        best_val = cur[i]
        best_score = cur_score

        for v in range(1, n + 1):
            if v == cur[i]:
                continue

            cur[i] = v
            score = ask(cur)

            if score > best_score:
                best_score = score
                best_val = v

            if score == n:
                return

            cur[i] = best_val

        cur[i] = best_val
        cur_score = best_score

    # final check
    ask(cur)

if __name__ == "__main__":
    solve()
```该代码维护当前候选数组并就地更新它。 对于每个位置，它会尝试所有可能的颜色，并只保留提高全局分数的颜色。 每次查询后的刷新至关重要，因为交互协议依赖于立即输出传递。 分数达到时提前终止$n$防止解决后不必要的查询。 

一个微妙的细节正在恢复`cur[i]`每次失败的试验后立即。 如果没有这个，以后的查询将累积不正确的临时状态并破坏分数解释。

 ## 边缘情况

 一个关键的边缘情况是多个值给出相同的分数。 例如，如果当前的猜测已经匹配许多位置，则更改错误的位置可能不会立即增加分数，因为这是在其他地方补偿错误。 该算法避免了陷入困境，因为它仅在有严格改进时才提交更改。 

考虑隐藏数组$[1,1,1,1]$和目前的猜测$[1,2,2,2]$。 分数为 1。将单个错误位置从 2 更改为 1 会将分数增加到 2，因此算法一次正确修复一个坐标。 如果更改没有提高分数，则会立即丢弃，以防止漂移。 

这确保了算法永远不会接受有害的修改，并且每个接受的移动都会严格增加正确性，保证最终在正确的数组处终止。
