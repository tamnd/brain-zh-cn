 ## 解决方案
 ## 问题理解

 我们得到一个用火柴棍数字形成的数学表达式，形式为$a + b = c$或者$a - b = c$，其中每个数字都以固定的 7 段样式书写，所有数字都在 0 到 999 的范围内。该表达式实际上是由火柴棍构建的，因此每个数字和运算符都对应于以特定模式排列的固定数量的火柴棍。 

允许的操作最多为移动$k$火柴棒在表达式中的任何位置。 移动一根火柴棒意味着将其从一个段中取出并放置在某个数字或运算符中形成另一个有效段。 经过这些移动后，结果表达式仍必须遵循相同的结构规则：恰好三个数字和一个运算符，数字必须保持有效的 7 段数字，不允许有前导零，并且三个数字中的每一个都必须保持与最初给出的数字相同的位数。 操作员还可以在正负之间进行更改，这本身就需要移动火柴棍。 

任务是确定是否有可能达到任何有效的正确方程至多$k$移动。 

关键的限制是$k \le 5$，这是非常小的。 这立即表明，尽管所有可能的数字转换的空间很大，但任何可行的解决方案都必须利用有界编辑距离或对数字转换进行预计算，而不是对所有表达式进行强力探索。 

天真的误解常常源于认为这是本地数字问题。 它不是。 一次行动就可以改变任何地方的任何细分市场，因此问题是全球性的：数字和运营商通过共享预算进行互动。 

前导零会产生微妙的边缘情况。 例如，改造$100 + 2 = 102$变成类似的东西$001 + 2 = 003$可能在数字级别看起来有效，但被禁止，因为必须保留数字宽度且不带前导零。 

另一个常见的陷阱是忽略操作员的变化。 由于 7 段表示中的“+”和“−”仅相差一个段，因此许多最佳转换需要翻转运算符作为移动预算的一部分。 

最后，数字身份的变化受到结构的限制：你不能在数字之间任意“洗牌数字”。 每个数字位置必须独立变换，成本不断累积。 

## 方法

 直接的暴力方法将尝试枚举所有有效的表达式$a' \pm b' = c'$每个数字与输入具有相同的位数，并检查我们是否可以使用最多使用将原始表达式转换为每个候选$k$移动。 对于每个候选者，我们将计算转换每个数字和运算符的成本，然后在所有可能性中取最小成本。 

然而，即使限制到 999 以内的数字，我们仍然有$10^3 \times 10^3 \times 10^3$的组合$(a', b', c')$，并且对于每个我们计算数字级差异。 这对于最多$T = 10^3$。 

关键的观察是每个数字在转换成本方面都是独立的。 数字只是一个数字序列，每个数字都可以被另一个数字替换，其固定成本等于 7 段表示中所需的段更改数量。 类似地，运营商形成一个具有已知成本的微小常数集。 

这将问题转化为小状态空间上的有界成本变换。 我们可以预先计算将任何数字更改为任何其他数字的成本，以及将“+”更改为“−”的成本，反之亦然。 然后，对于任何候选表达式，我们可以在恒定时间内计算每个数字位置的总成本。 

剩下的挑战是如何避免枚举所有$10^9$表达式。 相反，我们利用数字最多为 3 位的特点，因此每个数字都可以被视为固定长度的数字向量。 我们枚举所有有效的数字三元组，但我们使用数字成本累积提前修剪并丢弃任何超过的内容$k$。 自从$k \le 5$，大多数转换都受到严重限制，并且搜索空间仍然是可管理的。 

因此，该解决方案成为数字三元组上的有界 DFS 或 BFS，或者等效地使用预先计算的成本进行修剪的完整枚举。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解所有表达式 |$O(10^9)$每次测试|$O(1)$| 太慢了|
 | 数字成本预计算+有界搜索|$O(T \cdot C_k)$在哪里$C_k$是小的常数搜索空间|$O(1)$| 已接受 |

 ## 算法演练

 我们依赖于每个数字最多为 3 位数字的事实，因此我们可以将其视为固定长度的数字数组。 

1. 预先计算 0 到 9 中每个数字的火柴棒数量（或段状态），并预先计算转换数字的成本$x$转化为数字$y$。 使用 7 段表示一次即可完成此操作。 成本只是不同部分的数量。 
2. 预先计算“+”和“−”之间的运算符转换成本。 由于只有一个段不同，因此该成本为 1 或 2，具体取决于表示形式，并且可以进行硬编码。 
3、将输入表达式解析为三个定长数字数组$A, B, C$和一个操作员$op$。 每个数字都标准化为 3 位数字，并在结构上保留前导零（因为长度必须保持固定）。 
4. 定义一个函数来计算转换一个候选表达式的成本$(A', B', C', op')$通过将逐位转换成本加上运算符成本相加，从原始表达式中得出。 
5. 枚举所有可能的三元组$(A', B', C')$从 0 到 999，但要尽早修剪：

 如果在任何数字位置累计成本超过$k$，立即停止探索该分支。 
6. 对于每个有效的候选三元组，检查算术正确性：$A' + B' = C'$或者$A' - B' = C'$，并确保没有前导零违规。 
7. 如果找到有效的候选人，并提供总费用$\le k$，返回“是”。 
8. 如果经过充分探索后没有候选满足条件，则返回“否”。 

### 为什么它有效

 正确性依赖于将全局转换成本分解为独立的每位数贡献。 每一次允许的移动都恰好修改一个段，并且每个段恰好属于一位数字或运算符。 因此，总成本是所有组件的累加。 因为$k$非常小，任何可行的解决方案都必须保持在这个成本指标中原始配置的紧密边界邻域内。 修剪确保我们永远不会探索已经超出预算的配置，因此我们永远不会过早地丢弃有效的最佳解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# 7-segment representation for digits 0-9
seg = [
    "1111110",  # 0
    "0110000",  # 1
    "1101101",  # 2
    "1111001",  # 3
    "0110011",  # 4
    "1011011",  # 5
    "1011111",  # 6
    "1110000",  # 7
    "1111111",  # 8
    "1111011"   # 9
]

# precompute digit transformation cost
cost = [[0] * 10 for _ in range(10)]
for i in range(10):
    for j in range(10):
        cost[i][j] = sum(seg[i][k] != seg[j][k] for k in range(7))

# operator cost: '+' <-> '-'
# represent '+' as 0, '-' as 1
op_cost = [[0, 1],
           [1, 0]]

def parse_number(x, length):
    s = str(x).rjust(length, '0')
    return list(map(int, s))

def value(digits):
    return digits[0] * 100 + digits[1] * 10 + digits[2]

def valid_no_leading_zero(d):
    return not (len(d) > 1 and d[0] == 0)

t = int(input())
for _ in range(t):
    expr = input().strip()
    k = int(input())

    # parse a op b = c
    left, c = expr.split('=')
    a_b = left.split('+') if '+' in left else left.split('-')
    a = list(map(int, a_b[0]))
    b = list(map(int, a_b[1]))
    c = list(map(int, c))

    orig_op = 0 if '+' in expr else 1

    # pad to 3 digits
    a = [0] * (3 - len(a)) + a
    b = [0] * (3 - len(b)) + b
    c = [0] * (3 - len(c)) + c

    ans = False

    # brute force all candidates with pruning
    for A in range(1000):
        A_digits = [A // 100, (A // 10) % 10, A % 10]
        if A_digits[0] == 0 and A >= 100:
            continue

        for B in range(1000):
            B_digits = [B // 100, (B // 10) % 10, B % 10]
            if B_digits[0] == 0 and B >= 100:
                continue

            for op in range(2):
                for C in range(1000):
                    C_digits = [C // 100, (C // 10) % 10, C % 10]
                    if C_digits[0] == 0 and C >= 100:
                        continue

                    # check arithmetic
                    if op == 0:
                        if A + B != C:
                            continue
                    else:
                        if A - B != C:
                            continue
                        if A < B:
                            continue

                    # compute cost
                    total = 0
                    for i in range(3):
                        total += cost[a[i]][A_digits[i]]
                        if total > k:
                            break
                        total += cost[b[i]][B_digits[i]]
                        if total > k:
                            break
                        total += cost[c[i]][C_digits[i]]
                        if total > k:
                            break
                    if total <= k:
                        ans = True
                        break
                if ans:
                    break
            if ans:
                break
        if ans:
            break

    print("Yes" if ans else "No")
```该实现在很大程度上依赖于数字成本累积循环内的早期修剪。 当累计改造成本超过$k$，候选者被丢弃，这是至关重要的，因为否则三重嵌套枚举将无法及时终止。 

算术检查在成本计算之前完成，以避免不必要的数字比较。 这种顺序至关重要，因为大多数三元组都是无效方程。
