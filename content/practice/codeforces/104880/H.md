 ## 问题理解

 我们正在计算有多少 8 数配置产生了一种非常具体的“矩阵恒等式”，但问题的真正内容比它最初出现的要简单。 

每个配置由八个整数组成，全部从 1 到 99 的范围内独立选择。这些数字被放入两个 2×2 矩阵中。 当这些矩阵相乘时，结果不是标准算术矩阵乘法。 相反，乘积的每个条目都是通过连接数字形成的：左上角的条目成为第一对的串联，右上角的条目成为第二对的串联，依此类推。 具体来说，该结构在成对变量之间强制施加四个独立的串联约束。 

对于每对数字，例如 x 和 y，我们通过在 x 后面紧跟十进制 y 来形成一个新整数。 例如，如果 x = 12 且 y = 34，则串联为 1234。该问题要求我们计算有多少种方法可以选择这八个数字，使得四个串联结果分别保持在给定范围 A、B、C 和 D 内。 

因此，该任务实际上是四个独立约束的计数问题，每个约束仅依赖于一对变量。 

约束足够小，直接扫描每对所有 99 × 99 种可能性已经是可行的。 隐藏结构是八个变量分成四个不相交的对，并且这些对之间除了计数相乘之外没有相互作用。 

这里的一个天真的错误是将问题视为真正的矩阵乘法恒等问题并尝试模拟算术矩阵乘法。 这会导致错误的建模，因为该操作根本不是基于加法的。 另一个常见的错误是假设对之间存在某种耦合，而实际上每个约束仅通过串联绑定两个变量。 

边缘情况主要来自串联中的数字边界。 例如，如果 x = 9 且 y = 99，则串联为 999，而不是 108 或 9 × 99。同样，前导零无关紧要，因为值严格介于 1 到 99 之间，因此每个数字都只有一位或两位数字。 

## 方法

 暴力破解的想法很简单：枚举从 1 到 99 的所有八个变量，并检查所有四个串联数字是否满足各自的界限。 这涉及到$99^8$配置，大约是$10^{16}$的情况，远远超出任何可行的计算。 

关键的观察结果是约束完全分离。 涉及(a，e)的条件独立于(b，f)、(c，g)和(d，h)。 每对都为最终计数贡献一个因素，总答案成为四个独立计数函数的乘积。 

因此，我们不再考虑八个变量，而是将问题简化为计算单个函数 F(X)：有序对 (x, y) 的数量，使得连接 x 和 y 产生不超过 X 的数字。一旦我们可以计算 F，答案就是 F(A) × F(B) × F(C) × F(D)。 

由于每个 F(X) 仅取决于 99 × 99 种可能性，因此我们可以通过在每个查询的恒定时间内进行枚举来直接计算它。 该结构足够小，除了识别独立性之外不需要高级优化。

 ## 算法演练

 我们将问题简化为计算数字串联约束上的函数。 

1. 对于给定的边界 X，迭代所有有序对 (x, y)，其中 x 和 y 的范围都是从 1 到 99。 

每对表示通过以十进制形式写 x 后跟 y 形成一个串联整数。 
2. 通过将 x 和 y 转换为字符串并连接它们来构造连接值，然后将结果解释为整数。 

这一步直接符合问题中串联的定义。 
3. 如果串联值小于或等于 X，则计算该对的数量。 

这强制执行与矩阵乘积的一项相对应的约束。 
4. 独立重复上述过程，计算 F(A)、F(B)、F(C) 和 F(D)。 
5. 将四个结果相乘以获得最终答案。 

这些计算的独立性来自于每个约束都涉及一对不相交的变量，因此选择有效的 (a, e) 不会限制 (b, f)、(c, g) 或 (d, h) 的选择。 

### 为什么它有效

 八个数字的每个有效配置均由四个独立的对选择唯一确定：(a, e)、(b, f)、(c, g) 和 (d, h)。 这些约束永远不会混合不同对之间的变量。 这意味着有效解集是四个独立有效对集的笛卡尔积。 计算笛卡尔积中的元素会乘以基数，因此最终答案正是四对计数的乘积。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def concat(x, y):
    return int(str(x) + str(y))

def count_pairs(limit):
    if limit <= 0:
        return 0
    res = 0
    for x in range(1, 100):
        for y in range(1, 100):
            if concat(x, y) <= limit:
                res += 1
    return res

def solve():
    A, B, C, D = map(int, input().split())
    print(count_pairs(A) * count_pairs(B) * count_pairs(C) * count_pairs(D))

if __name__ == "__main__":
    solve()
```该解决方案将问题分解为一个可重用的计数例程，用于评估所有 99 × 99 的串联。 通过字符串进行转换是安全的，因为界限很小，并且保证了数字连接的正确性，没有算术歧义。 

乘法步骤是关键的结构洞察：一旦独立计算每对贡献，完整的八个变量计数就是它们的乘积。 

## 工作示例

 考虑所有边界都很小的输入，例如：

 A = B = C = D = 50

 我们通过扫描所有对 (x, y) 来计算 F(50)。 仅计算连接形成的数字 ≤ 50 的对。 这本质上将我们限制为非常小的串联，例如 11、12、21、22、...、49、50，具体取决于数字结构。 大多数两位数串联（例如 101、234 甚至 99）与任何 y 的连接都会立即超过 50。 

| 步骤| 一个 | F（A）| 乙| 前（后）| C | 前线（中） | d | 前线（D）| 结果 |
 | ---| ---| ---| ---| ---| ---| ---| ---| ---| ---|
 | 输入 | 50 | 50 - | 50 | 50 - | 50 | 50 - | 50 | 50 - | - |

 迹线显示所有四个分量的行为相同，最终答案变为四次方。 

现在考虑一个更大的不对称情况：

 A = 9999，B = 12，C = 345，D = 6789

 对于 A = 9999，从 1 到 99 的两个数字的每次串联最多为 9999，因此 F(A) = 99 × 99 = 9801。对于 B = 12，只有非常小的串联（如 (1,1)、(1,2)、(2,1) 等）存活下来，因此 F(B) 很小。 这显示了函数如何根据数字阈值从饱和（所有对有效）转变为高度受限。

 ## 边缘情况

 一个重要的边缘情况是当边界非常小时，例如 X = 1。在这种情况下，只有串联产生恰好 1 的对才是有效的，这本质上意味着只有类似 (1, 0) 的结构才重要，但由于 y ≥ 1，几乎没有任何结构是有效的。 该算法仍然可以正确处理这个问题，因为它显式地检查每一对并仅计算满足不等式的那些。 

另一个边缘情况是当 X ≥ 9999 时。由于 [1, 99] 中两个数字的最大可能串联是 9999（从 99 到 99），所以每一对都有效。 该循环可以正确计算所有 9801 对，无需特殊外壳。 

最后一个微妙的情况是数字不对称，例如 x = 1 和 y = 99 产生 199，这可能会或可能不会超过 X，具体取决于其大小。 无论数字长度如何，基于字符串的串联都能确保正确的解释，因此不需要算术边缘处理。
