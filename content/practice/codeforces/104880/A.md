 ## 解决方案
 ## 问题理解

 我们得到一个固定的时间表，编码为长度为 24 的二进制字符串。每个位置对应于一天中的一小时，从第 1 小时到第 24 小时。一个字符`1`表示您在该时间段内工作，而`0`意味着你正在休息。 

使时间表无效的唯一条件是存在连续六个工作时间段。 如果一天中的任何地方存在一个完全由六个组成的连续子串`1`人物，时间表被认为是有害的。 否则，这是可以接受的。 

任务只是确定是否存在这样的禁止块。 

尽管输入大小固定为 24，但问题的结构暗示了短序列上的一般模式识别任务。 任何检查长度为 6 的每个可能的连续段的解决方案都将在恒定时间内运行，因为 24 长度的字符串中只有 19 个这样的段。 

一种常见的边缘情况来自逐一扫描逻辑。 例如，给定`111110111111`，一个粗心的实现，只检查不相交的块，例如`[1..6], [7..12]`会错误地错过跨越边界的跑步。 另一个微妙的问题是忘记了游程可以出现在任何地方，不一定与六的倍数对齐。 

正确的处理需要检查所有重叠的大小为 6 的窗口。 

## 方法

 解决该问题的一种暴力方法是检查每个可能的长度为 6 的连续子串，并验证该子串中的所有字符是否都是`1`。 由于字符串长度为 24，因此有 24 − 6 + 1 = 19 个这样的子字符串。 对于每个子字符串，检查其有效性需要检查 6 个字符，因此总工作量是恒定的并且非常小。 

这种暴力方法在此设置中已经是最佳的，因为输入大小是固定的并且很小。 然而，从概念上来说，考虑一个更通用的版本是有用的，其中字符串长度为`n`。 在这种情况下，简单的方法将检查大小为 6 的所有窗口，从而导致 O(n) 个窗口和 O(6n) 次总检查，从而简化为 O(n)。 

关键的观察结果是，我们不是在子字符串上计算复杂函数，而是简单地检测是否存在长度至少为 6 的游程。 这使得问题相当于跟踪当前连续的连续`1`s。 我们可以维护一个正在运行的计数器，并在任何时候重置它，而不是重复地重新扫描子字符串。`0`遇到。 当计数器达到6时，我们可以立即停止。 

这将逻辑从滑动窗口检查减少到具有恒定内存的单遍。

 ## 算法演练

 1.初始化一个计数器`run`为零。 该变量表示当前连续的长度`1`到目前为止我们已经看到了。 
2. 从左到右遍历字符串中的每个字符。 
3. 如果当前字符是`1`, 增量`run`1，因为连胜仍在继续。 
4. 如果当前字符是`0`， 重置`run`为 0，因为任何连续序列都被破坏。 
5.更新后`run`，检查是否达到6，如果达到，则立即判定排班无效，停止处理。 
6. 如果循环完成但未达到 6，则调度有效。 

关键的想法是，我们永远不需要记住比当前的连续性更多的内容，因为任何未来的有效块都必须是连续的，并且任何中断都会使之前的连续性失效。 

### 为什么它有效

 在字符串中的任何索引处，值`run`完全等于在该位置结束的最长后缀的长度，仅包含`1`s。 这意味着每个可能的连续块`1`s 隐式表示为以下值`run`在扫描过程中的某个时刻。 如果任何地方都存在长度为 6 的块，那么当我们到达它的最后一个字符时，`run`必须至少为 6，触发检测。 相反，如果不存在这样的块，`run`永远不会达到 6，因此算法正确地接受了时间表。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()

run = 0
for ch in s:
    if ch == '1':
        run += 1
        if run >= 6:
            print("NO")
            break
    else:
        run = 0
else:
    print("YES")
```该解决方案读取 24 个字符的时间表并维护一个整数计数器。 该循环使用Python的`for-else`结构，以便仅在没有发生早期中断时才打印“YES”。 尽早退出很重要，因为一旦发现有效违规行为，就不需要进一步扫描。 

一个常见的实现错误是在遇到以下情况时忘记重置计数器`0`，这会错误地将分离的运行合并为一个连续的段。 另一个微妙的问题是仅在循环之后而不是在迭代期间进行检查，这将防止提前终止，但由于输入大小较小而仍然保持正确。

 ## 边缘情况

 一个关键的边缘情况是当正好六个连续的`1`s 出现在字符串的开头。 用于输入`111111000000000000000000`，计数器在索引 6 处达到 6，算法立即打印`NO`。 这证实了检测不依赖于位置并且在边界处正确工作。 

另一种情况是当两次运行五次`1`s 由单个分隔`0`， 例如`111110111110...`。 零处的重置确保第二次运行重新开始，并且都没有达到长度 6，因此输出保持不变`YES`。 

最后一种情况涉及交替字符，例如`101010...`。 计数器反复重置为 1，从不累加，因此算法安全返回`YES`没有任何误报的风险。
