 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串的集合，每个字符串的长度相等。 您可以将每个字符串视为以 2 为基数编写的具有固定位数的数字。 对于每对字符串，我们计算它们的按位异或，将生成的二进制字符串解释为整数，对其进行平方，然后将所有带索引的对的值相加$i \le j$。 

对角线对其中$i = j$不要贡献任何东西，因为数字与其自身的异或为零。 因此，问题的真正内容是对所有无序的不同字符串对的总贡献，但仍然以尊重 XOR 结果平方值的方式累积。 

这些限制以非常具体的方式发挥作用。 所有字符串的输入位数最多为$5 \cdot 10^6$。 这是关键的限制：我们可以读取和处理所有位，但任何缩放比例如$n^2$或者$m^2$不小心就会立即不安全。 尝试显式计算每对的 XOR，然后对其进行平方的解决方案将需要大约$O(n^2 m)$，当两个维度都相当大时，它就已经失败了。 

幼稚的方法也会忽略一个更微妙的问题。 即使 XOR 值可以有效计算，对它们进行平方也会隐藏跨位交互。 这意味着单独处理每个位是不够的； 位位置之间的相互作用有助于最终的答案。 

作为具体的失败案例，请考虑两个数字，例如`011`和`101`。 他们的异或是`110`，即 6，其平方为 36。如果我们尝试独立地对每位贡献求和，我们将考虑$2^2$来自每个设置位但错过了交互项$2 \cdot 2^2 \cdot 2^1$。 缺少的交叉项正是天真的按位求和的突破点。 

## 方法

 暴力解决方案很简单。 对于每对字符串，计算它们的异或，将其转换为整数，对其求平方，然后将其添加到答案中。 XOR 本身的成本$O(m)$，并且有$O(n^2)$对，因此总复杂度变为$O(n^2 m)$。 和$n m \le 5 \cdot 10^6$，在最坏的情况下，这太大了$n$和$m$大约有几千或更多。 

关键的观察结果是平方异或可以扩展到比特贡献。 如果我们将 XOR 的值写为带有权重的位的总和$2^k$，则平方产生两种类型的项：单个位位置的贡献和位位置对之间的相互作用。 这将问题转变为对所有字符串对进行计数，计算它们在一位位置上不同的频率以及它们在两个位置上同时不同的频率。 

单比特部分很容易处理。 对于每个位位置，我们只需要知道有多少对字符串在该位上不同。 这可以根据该列中 1 和 0 的数量来计算。 

困难在于两个不同位位置之间的相互作用。 直接的解决方案需要迭代所有位位置对并计算两个位置上有多少个字符串对不同。 这看起来是二次方$m$，但约束$n \cdot m \le 5 \cdot 10^6$保证位矩阵至少在一维上是稀疏的。 这使我们能够转置问题并使用基于位集的计数，以便可以使用字级操作有效地处理每对位位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2 m)$|$O(1)$额外 | 太慢了|
 | 位计数+成对位交互|$O\left(\frac{m^2 n}{64}\right)$结构最差但受约束 |$O(nm)$| 已接受 |

 ## 算法演练

 我们将输入视为$n \times m$二进制矩阵，其中行是数字，列是位位置。 

1. 构建输入的转置表示，以便每个位位置$k$存储长度的位集$n$。 这让我们可以快速比较所有数字的两个位位置。 
2. 对于每个位位置$k$，计算有多少对字符串在该位上不同。 这是通过计算该列中的 1 和 0 来完成的。 如果有$c_1$那些和$c_0$零，则不同对的数量为$c_0 \cdot c_1$。 这通过以下方式直接影响平方异或：$2^{2k}$重量。 
3. 对于每对位位置$(k, l)$和$k < l$，计算有多少对字符串在两个位置上都不同。 使用位集，我们计算有多少字符串属于由位确定的四个类别中的每一个类别$(k, l)$:`00`,`01`,`10`， 和`11`。 
4. 根据这些计数，计算两个位不同的字符串对的数量：$$\text{cnt}_{00} \cdot \text{cnt}_{11} + \text{cnt}_{01} \cdot \text{cnt}_{10}.$$该值有助于与权重的交叉项$2 \cdot 2^k \cdot 2^l$。 
5. 将单位和跨位贡献累加到最终答案模中$998244353$。 

### 为什么它有效

 平方 XOR 值在位指示符上展开为二次形式。 每个贡献仅取决于两个字符串在每个位位置是否不同，而不取决于字符串的实际身份。 这意味着整个问题简化为计算位之间的成对分歧模式。 一旦知道了所有单比特和成对比特的不一致计数，展开式中的每一项就只计算一次，并且不存在高阶交互。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modpow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

n, m = map(int, input().split())
a = [input().strip() for _ in range(n)]

# store columns as bit arrays (as Python integers bitsets over rows)
col = [0] * m
for i in range(n):
    row = a[i]
    for j, ch in enumerate(row):
        if ch == '1':
            col[j] |= (1 << i)

ans = 0

# precompute powers of 2 up to 2m
pw = [1] * (m + m + 5)
for i in range(1, len(pw)):
    pw[i] = pw[i - 1] * 2 % MOD

# single-bit contributions
for k in range(m):
    ones = col[k].bit_count()
    zeros = n - ones
    cnt = ones * zeros
    w = pw[2 * k]
    ans = (ans + cnt * w) % MOD

# pair-bit contributions
for k in range(m):
    bk = col[k]
    for l in range(k + 1, m):
        bl = col[l]

        both_1 = (bk & bl).bit_count()
        only_k = (bk & ~bl).bit_count()
        only_l = (~bk & bl).bit_count()
        both_0 = n - both_1 - only_k - only_l

        cnt = both_0 * both_1 + only_k * only_l

        w = pw[k + l + 1]  # 2 * 2^k * 2^l = 2^(k+l+1)
        ans = (ans + cnt * w) % MOD

print(ans % MOD)
```该实现首先将每列转换为行上的位集，这使得以后使用按位运算可以快速计算交集。 第一个循环使用基于选择在该位不同的两个字符串的简单组合参数来计算各个位位置的贡献。 

第二个嵌套循环处理位位置对之间的交互。 位集允许我们计算四个联合分布$(k, l)$有效地使用 AND 运算和补码。 根据这四个计数，我们重建了有多少对在两个位上都不同，并乘以从二进制扩展得出的正确权重。 

指数$k + l + 1$重量来自膨胀$2 \cdot 2^k \cdot 2^l = 2^{k+l+1}$，它避免了浮点运算并将所有内容保留在模运算中。

 ## 边缘情况

 单个字符串输入立即结果为零，因为没有对。 该算法自然地处理这个问题，因为所有对计数器都保持为零。 

当所有字符串都相同时，每列要么全为零，要么全为 1，使得每个贡献都为零。 位集交集也会正确折叠，因为不存在不同的对。 

当所有字符串中只有一个位位置变化时，跨位循环不会产生任何影响，因为没有第二个变化维度，并且答案减少为单列组合计数。 

这些案例证实，当结构退化时，单比特和双比特部件都会正确降解，而不需要特殊处理。
