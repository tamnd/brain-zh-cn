 ## 解决方案
 ## 问题理解

 我们得到了多组石头类型，其中每种类型都有一个值和一个数量。 总共正好有$2n$石头，因此每块石头必须在配对中恰好使用一次。 

当我们将两颗宝石与价值配对时$x$和$y$，他们贡献的分数等于$(x + y) \bmod k$。 目标是将所有石头配对，以便这些模块贡献的总和$n$对最大化。 

重新解释评分的一个有用方法是将每对分为两种情况。 如果$x + y < k$，贡献很简单$x + y$。 如果$x + y \ge k$，贡献变为$x + y - k$。 每一次“溢出过去$k$” 成本正好$k$。 由于所有石头的所有值的总和是固定的，因此最大化最终答案相当于最大化至少有多少对具有总和$k$。 每对这样的对都会减少总数$k$，因此我们希望尽可能避免这些减少，或者同等地控制哪些对被迫跨越阈值。 

输入大小使得暴力破解变得不可能。 石头的总数可能非常大（最多可达约$2 \cdot 10^9$约束中最差解释的元素），而不同值的数量最多为$2 \cdot 10^5$。 任何显式枚举所有宝石或尝试所有配对的算法都是不可行的。 甚至$O((2n)^2)$或者$O(n \log n)$由于内存和时间的原因，扩展元素会失败。 

天真的贪婪方法的一个微妙的失败案例是假设在不正确考虑多重性的情况下，对单个宝石进行排序并配对极端值始终是最佳的。 如果在扩展数组上简单地实现，它也会立即达到内存限制。 另一种不正确的方法是将每个石头与最大可能的有效伙伴独立地贪婪地配对，这可能会破坏全局最优性，因为它忽略了早期消耗大值可能会阻止未来更好的配对。 

## 方法

 蛮力的想法很简单：将所有石头展开到一个列表中，并尝试所有可能的完美匹配，计算每个石头的分数。 这是正确的，因为它探索了整个解决方案空间，但匹配的数量是$(2n)! / (2^n n!)$，呈超指数增长。 即使对于非常小的$n$，这已经是不可行的，并且对于给定的约束，这是完全遥不可及的。 

关键的观察结果是，分数仅取决于一对是否跨越阈值$k$，否则不在精确的配对总和上。 一旦重写，问题就变成了：最大化总和至少为的对的数量$k$。 所有剩余的配对都会自动贡献全部金额，而不会受到处罚。 

这将问题转化为排序多重集上的结构化匹配问题。 我们只关心哪对“成功”（交叉$k$），哪些没有。 最优策略源自经典的贪婪原理：始终尝试将最小可用值与最大可用值进行匹配，因为这种配对穿过阈值的机会最高。 如果连这一对都达不到$k$，那么最小的元素太小，无法帮助任何其他配对达到阈值，因此必须以无益的方式进行配对。 

这将问题简化为对按频率排序的值数组的两指针处理，小心地消耗计数而不是扩展列表。

 ## 算法演练

 我们将输入压缩为值和频率对，然后按值对它们进行排序。 

我们维护两个指针，一个位于最小值类，一个位于最大值类。 

1. 初始化指针$l = 0$,$r = m - 1$，和一个变量`success = 0`。 
2. 虽然$l \le r$，考虑当前值类别$v_l$和$v_r$。 
3.如果$l = r$，我们在同一值组内配对。 我们可以形成的对的数量是$\lfloor c_l / 2 \rfloor$。 我们检查是否$2v_l \ge k$。 如果是，则所有这些配对都成功； 否则对最佳计数没有贡献。 
4.如果$v_l + v_r \ge k$，然后将最小的与最大的配对保证成功。 我们尽可能多地配对，即$\min(c_l, c_r)$。 每对这样的配对都会贡献一对成功的配对。 我们相应地减少这两个计数，并移动耗尽的一侧的指针。 
5. 如果$v_l + v_r < k$，那么即使是最大的可能合作伙伴$v_l$无法到达$k$。 这意味着$v_l$不能参加任何成功的配对。 我们通过移动来放弃它$l$向前，有效地将其质量推入不可避免的非成功对。 
6. 继续，直到所有计数都消耗完。 

答案是找到的成功对的数量。 

### 为什么它有效

 该算法依赖于结构优势论证。 当我们对值进行排序时，剩余集合中最大的元素是任何较小元素的最佳伙伴。 如果那个最佳伴侣仍然不足以达到阈值，那么没有其他配对可以帮助这个小元素促成成功的配对。 因此，尽早删除它并不能减少成功配对的最佳数量。 

当最小和最大之间存在成功配对时，将它们配对总是安全的，因为用更极端的替代方案替换任一端点是不可能的：端点已经是极端。 这确保了我们永远不会因为贪婪地消耗它们而失去潜在的成功。 

该过程保留了所有剩余的不匹配元素仍然具有至少一个与当前极值的潜在有效配对的不变性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    v = list(map(int, input().split()))
    
    pairs = sorted(zip(v, a))
    
    l, r = 0, m - 1
    success = 0
    
    while l <= r:
        vl, cl = pairs[l]
        vr, cr = pairs[r]
        
        if l == r:
            # pair within same group
            if vl * 2 >= k:
                success += cl // 2
            break
        
        if vl + vr >= k:
            t = min(cl, cr)
            success += t
            pairs[l] = (vl, cl - t)
            pairs[r] = (vr, cr - t)
            if pairs[l][1] == 0:
                l += 1
            if pairs[r][1] == 0:
                r -= 1
        else:
            # vl cannot form success with any vr
            l += 1
    
    print(success)

if __name__ == "__main__":
    solve()
```该代码首先将多重集压缩为值计数对并对它们进行排序。 然后，两个指针模拟贪婪地消耗这些计数。 当一对有效时，我们会耗尽尽可能多的匹配质量，因为每个这样的配对都会独立地贡献一个成功的结果。 当一对无效时，我们可以安全地丢弃较小的一侧，因为它无法通过任何其他配对来挽救。 

更新计数时必须小心：未能正确递减或前进指针会导致无限循环或重复计数。 单值情况也必须单独处理，因为配对发生在同一个存储桶内。
