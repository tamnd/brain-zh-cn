 ## 解决方案
 ## 问题理解

 我们有一群人沿着无限直线移动。 每个人都从一个位置开始$x_i$然后匀速移动$v_i$。 所有运动都在同一时刻开始，所以时间$t = 0$是共享的。 

每当两个人同时到达同一位置时，他们就会一起拍照。 如果有一组$k$人们在同一时间在同一地点见面，该组中的每一对都拍一张照片，这样就做出了贡献$\frac{k(k-1)}{2}$那一瞬间的照片。 我们需要所有时间中此类配对会议的总数。 

关键对象不是运动本身，而是位置的相等性：$$x_i + v_i t = x_j + v_j t$$它定义了两个人何时见面（如果有的话）。 

限制因素$n \le 1000$和$|x_i|, |v_i| \le 10^4$立即建议$O(n^2)$推理是安全的。 任何试图连续模拟时间或动态跟踪事件的解决方案都是不必要的，而且可能过于复杂。 

一个微妙的问题是处理同时举行的会议。 多对可以在完全相同的时间和地点相遇，形成一个集群。 例如，如果三个人都满足相同的路口时间和位置，那么我们必须算3张照片，而不是2或1张。 

另一个边缘情况来自相同的起始位置。 如果$x_i = x_j$，无论速度如何，它们都会在时间 0 立即相遇，因此它们一开始就贡献一张照片。 仅检查具有正时间的交叉点的简单实现会错过这些。 

最后，在某些情况下，两条轨迹永远不会相遇，因为它们的相对运动在向前的时间中不相交，例如当速度更快的人开始前进时。 

## 方法

 暴力方法检查每一对人并计算他们的轨迹是否相交。 一对$(i, j)$，我们解决：$$x_i + v_i t = x_j + v_j t$$这给出：$$t = \frac{x_j - x_i}{v_i - v_j}$$如果$v_i = v_j$，只有当$x_i = x_j$，否则永远不会。 如果$t \ge 0$，我们算一次会议。 

这是有效的，因为每个有效对都对应于一个会议事件。 正确性很简单，但它并没有以分组的方式显式地处理多人碰撞。 然而，成对计数已经足够了，因为每次会议对每对都有独立的贡献。 

仅当我们尝试除配对枚举之外的任何操作（例如按时间对事件进行排序或模拟运动）时，问题才会出现。 这需要处理最多$O(n^2)$事件并对它们进行排序，导致$O(n^2 \log n)$，这是不必要的。 

关键的见解是我们根本不需要模拟时间。 每次会议纯粹由成对代数决定，直接计算所有有效对就已经产生了正确的答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力配对检查 | O(n²) | O(1) | O(1) | 已接受 |
 | 事件模拟/排序| O(n² log n) | O(n² log n) | O(n²) | 已接受但没有必要 |

 ## 算法演练

 1. 迭代所有无序的人对$(i, j)$。 这确保了每个可能的交互都被恰好考虑一次。 
2.如果$v_i = v_j$，检查是否$x_i = x_j$。 如果是这样，那么这两个人从一开始就一直在一起，所以他们贡献的正是一张照片。 否则，他们永远不会见面，也不会做出任何贡献。 
3.如果$v_i \ne v_j$，使用以下方法计算会议时间：$$t = \frac{x_j - x_i}{v_i - v_j}$$这是直接通过将它们随时间的位置相等而得出的。 
4. 仅计算该对，如果$t \ge 0$。 负时间对应于过去的会议，这是无关紧要的，因为运动开始于$t = 0$。 
5. 累加有效对的总数。 

为什么它有效：

 每对人都有一个由线性运动决定的独特的潜在见面时间。 如果该时间存在且非负，则两人恰好贡献了一张照片。 即使多个人同时在同一点相遇，该组内的每一对仍然被独立计数，因此成对累加自然地捕获组碰撞而无需特殊处理。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
people = [tuple(map(int, input().split())) for _ in range(n)]

ans = 0

for i in range(n):
    x1, v1 = people[i]
    for j in range(i + 1, n):
        x2, v2 = people[j]

        if v1 == v2:
            if x1 == x2:
                ans += 1
            continue

        num = x2 - x1
        den = v1 - v2

        if den == 0:
            continue

        # check if t >= 0 without floating point
        # t = num / den >= 0  <=> num and den have same sign
        if num * den >= 0:
            ans += 1

print(ans)
```该实现直接反映了成对推理。 循环结构枚举了所有对$O(n^2)$。 等速情况被分开，因为否则划分将是无效的，并且在概念上对应于永久重叠或永不相遇。 

条件`num * den >= 0`通过检查分数的符号而不是显式计算它来避免浮点精度问题。 这很重要，因为位置和速度是整数，但除法可能会引入微妙的浮点错误。

 ## 边缘情况

 当多人从同一位置开始时，其中的每一对都会立即计数。 用于输入`3 0 1 0 2 0 3`，该算法评估所有三对并且每对都满足`x1 == x2`，因此它返回 3，与所有对在时间零相遇的事实相匹配。 

当速度相同但位置不同时，例如`2 0 1 10 1`，条件`v1 == v2`触发并跳过计数，正确反映平行运动永不相交。 

当速度更快的人开始领先时，比如`0 2`和`10 1`，计算出的分子和分母具有相反的符号，因此`num * den >= 0`失败，从而阻止对无效的“向后时间”会议进行计数。
