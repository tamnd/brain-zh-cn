 ## 问题理解

 我们有一棵有 _n_ 个顶点的树，其中每条边都带有非负权重。 对于任意两个顶点，它们之间的距离可以通过两种方式测量：沿连接它们的路径的边数，以及沿该路径的边权重之和。 如果存在连接两个顶点的路径，并且该路径最多包含 _l_ 条边并且总权重不超过_w_，则两个顶点被视为_close_。 任务是计算满足此紧密度标准的所有无序不同顶点对。 

输入结构是增量的：每条边将顶点_i+1_连接到之前的某个顶点_pᵢ_，因此树本质上以顶点1为根。树最多有10^5个顶点，边权重可以达到10^4。 路径长度限制_l_也可以达到10^5，而权重限制_w_可以大到10^9。 

考虑到 _n_ 的大小，任何显式检查所有对的算法都会太慢。 暴力破解会涉及 O(n²) 次比较，在最坏的情况下大约需要 10^10 次操作，远远超出了可行的范围。 这表明我们需要一种更复杂的方法来利用树结构来避免冗余计算。 

当限制 _l_ 或 _w_ 非常小（可能排除几乎所有对）或非常大（有效地计算几乎所有对）时，就会出现边缘情况。 不修剪不可行路径的幼稚方法既会浪费时间，也会产生错误的结果。 例如，由三个顶点组成的树，其边权重为 10，并且限制 _l_ = 1、_w_ = 5，应该产生零个闭合对。 对所有相邻节点进行计数的粗心 DFS 会错误地产生非零计数。 

## 方法

 暴力解决方案将考虑每对顶点，使用 BFS 或 DFS 计算路径长度和权重，如果两个条件都满足，则增加计数器。 虽然正确，但这种方法在路径跟踪方面的时间复杂度为 O(n²)，空间复杂度可能为 O(n)。 显然，它在问题的 10^5 个顶点的上限处失败。 

优化的关键见解是我们正在处理一棵树。 树没有循环，这使得分而治之的方法能够有效地工作。 一种有效的方法是质心分解。 通过递归地选择质心，我们可以将树分成更小的子树，并计算经过质心的路径的紧密对。 对于每个子树，我们执行约束 DFS 来收集距离和权重，然后将结果与高效的数据结构（如二元索引树（芬威克树）或多重集）相结合，以计算有多少条路径满足这两个约束。 

这种方法利用了这样一个事实：每条路径要么通过质心，要么完全位于单个子树内。 单独处理通过质心的路径允许我们合并子树而无需重复计算，并避免冗余的配对检查。 分解保证每个顶点都涉及 O(log n) 个质心级别，从而给出 O(n log n) 的整体复杂度。

 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 质心分解 + Fenwick 树 | O(n log n) | O(n log n) | | |
