 ## 解决方案
 ## 问题理解

 工厂有一排从左到右索引的灯。 每个灯都以“开”状态开始。 Mashmokh 执行一系列按钮按下操作，每个按钮都有一个索引，用于确定其效果向右延伸多远。 

当带有索引的按钮`i`按下后，它会扫描该位置的所有灯光`i`直到最后并关闭它遇到的每一个仍然亮着的灯。 已经熄灭的灯保持熄灭，之前的灯`i`不受影响。 

任务是确定对于每个灯，按下哪个特定按钮会导致其第一次关闭。 我们不会被问到它受到了多少次影响，或者后来发生了什么，只有按序列中最早的按键将其关闭。 

限制很小：灯的数量和按钮按下的次数最多为 100。这立即排除了对高级数据结构或对数优化的任何需要。 即使是简单的二次模拟也能在时间限制内轻松完成，因为操作总数保持在一万左右。 

一个微妙的问题是按钮不能保证是有序的。 后面的按钮可能比前面的按钮具有更小的索引，这会改变受影响的灯以及它们何时关闭。 另一个重要的细节是，一旦灯关闭，以后的按键就无法更改其记录的答案。 

一个天真的错误是假设每个按钮只影响与之前的按下无关的固定部分。 例如，如果我们忽略“仍然打开”条件，我们可能会重复错误地覆盖答案。 

考虑这个小场景：

 输入：```
3 2
2 1
```正确的行为：

 按 2 后，灯 2 和 3 熄灭，因此两者都被分配为按钮 2。按 1 后，灯 1 熄灭并被分配为按钮 1。 

不小心的模拟会再次关闭已经关闭的灯，可能会错误地覆盖答案或尝试多次重新分配答案。 

关键是每个灯必须在它从开到关的时刻被精确分配一次。 

## 方法

 思考该过程的最直接方法是完全按照描述进行模拟。 我们维护一个表示每个灯是否打开的数组，以及另一个存储每个灯的答案的数组。 对于每次按下按钮，我们都会扫描所有受影响的灯光（从其索引到`n`，每当我们遇到仍然亮着的灯时，我们都会通过此按钮将其标记为关闭。 

这种方法是正确的，因为它一步一步地反映了工厂的流程。 问题是效率：在最坏的情况下，每个`m`印刷机最多可扫描`n`灯，导致大约`n * m`运营。 在给定的约束下，这仍然可以接受，因为最多只能进行 10,000 次操作。 

稍微更概念化的观察可以简化推理。 一盏灯`j`当我们第一次遇到索引小于或等于的按钮时关闭`j`在序列中。 具有较大索引的早期按钮不会对其产生影响，并且一旦出现有效按钮，灯就已经熄灭并且永远不会再次被考虑。 这一观察结果与模拟相符，并解释了为什么单次通过每个灯和按钮就足够了。 

因此，直接模拟和派生的“第一排位赛新闻”观点都会导致相同的实现结构。

 ## 算法演练

 我们以直接对应于过程如何展开的方式来描述模拟。 

1.初始化一个数组`ans`尺寸的`n`，用零填充。 这将存储关闭每个灯的按钮索引。 还维护一个布尔数组`on`初始化为all tr​​ue，代表所有灯一开始都是亮的。 
2. 按给定顺序从第一次按下到最后一次按下按钮。 
3. 对于每个带索引的按钮`b_k`，从位置扫描所有灯`b_k`通过`n`。 
4. 如果位置有灯`j`仍然开启，分配`ans[j] = b_k`并将其标记为关闭。 
5. 如果灯已经熄灭，则跳过它，因为其结果是之前确定的并且无法更改。 
6. 继续，直到处理完所有按钮按下操作。 

我们仅在灯仍然亮着时进行分配的原因是，我们正在捕获其第一次转换为关闭状态的确切时刻。 任何后来也覆盖该位置的按钮都必须被忽略。 

### 为什么它有效

 每个灯的状态从开到关只改变一次。 第一次有索引的按钮`b_k ≤ j`已加工，光`j`仍然打开，因为没有早期的按钮可以覆盖它。 该新闻必然包括`j`在其范围内并将其关闭。 从那一刻起，任何后续操作都不会影响其记录的答案，因为我们明确防止覆盖。 这保证了`ans[j]`存储到达它的最早的有效新闻。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    b = list(map(int, input().split()))

    ans = [0] * n
    on = [True] * n

    for btn in b:
        i = btn - 1
        for j in range(i, n):
            if on[j]:
                on[j] = False
                ans[j] = btn

    print(*ans)

if __name__ == "__main__":
    solve()
```该解决方案遵循前面描述的精确模拟。 数组`on`确保每个灯仅分配一次。 内循环从`btn - 1`因为灯光在实现中是 0 索引的，而输入是 1 索引的。 

一个常见的陷阱是忘记一旦灯关闭，后面的按钮就不能覆盖它的答案。 条件检查`if on[j]`强制执行这个不变量。

 ## 边缘情况

 最小单灯情况检查实现是否正确处理索引并且不会尝试访问无效范围。 什么时候`n = 1`, 任意按钮`1`立即关掉唯一的灯，任务就很简单了。 

当按钮严格增加时，每次按下往往只会影响尚未发现的后缀。 该算法在其索引第一次被覆盖时准确地分配每个灯，从而在位置和最早的合格按钮之间产生直接映射。 

当按钮严格减少时，第一次按下就已经涵盖了几乎所有内容。 在这种情况下，内循环仍然正确运行，但只赋值一次，稍后按发现没有活动灯可以修改。 这证实了`on`数组正确防止覆盖。 

当覆盖范围严重重叠时，早期的大范围压力可能会抢先后来的小范围压力。 条件`if on[j]`确保一旦分配了灯光，它就保持固定，即使在激进的重叠模式下也能保持正确性。
