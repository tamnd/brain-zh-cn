 ## 解决方案
 ## 问题理解

 每天，Mashmokh 都会收到一堆代币，当天结束时，他可以使用固定的兑换规则将其中一些代币兑换成金钱。 如果他回来$w$代币，他获得的钱仅取决于有多少个完整的“区块”大小$a$包含在线性函数中$w$。 精确的映射是线性的，然后是下限的，因此下一个货币单位的零碎进展毫无价值。 

关键目标不是最大化直接转换的代币，而是最大化金钱，同时节省尽可能多的代币。 由于未使用的代币不会延续到未来的日子，因此每一天都是独立的，我们只需要决定当天交换多少代币即可达到最大可能的货币价值。 

输入给出$n$天数、参数$a$和$b$，和一个数组$x_i$描述每天有多少代币可用。 每天的输出是选择最佳兑换金额后可以保存多少代币。 

约束条件$n \le 10^5$迫使$O(n)$或者$O(n \log n)$解决方案。 任何涉及每天模拟所有可能的代币选择的事情都会太慢，因为$x_i$可以大到$10^9$，使得暴力破解变得不可行。 

出现微妙的边缘情况时$x_i$相比之下非常小$a$。 例如，如果$x_i < a$，根据公式，可能无法进行交换，并且像“使用所有代币”这样天真的贪婪假设将会失败。 另一个边缘情况是当$x_i$恰好位于多重边界上，其中增加交换的代币不会增加金钱，这意味着节省一个额外的代币总是最佳的。 

## 方法

 直接的方法是尝试所有可能数量的令牌$w$从$0$到$x_i$，计算所得的钱，并选择最好的一个，同时最大化关系中的剩余代币。 这是正确的，但速度非常慢。 对于每一天我们都会做$O(x_i)$工作，在最坏的情况下变成$O(n \cdot 10^9)$，完全不可能。 

货币函数的结构是关键的观察结果。 钱只取决于$\left\lfloor \frac{a \cdot w}{b} \right\rfloor$，因此该值仅在离散阈值处增加$w$。 在两个连续阈值之间，增加$w$不换钱。 这意味着我们永远不需要考虑所有的值$w$，只有最小的$w$在约束下达到最大可能的整数值$w \le x_i$。 

对于固定的$x_i$，最佳策略是计算使用所有代币可获得的最大金钱，然后找到达到相同金钱水平所需的最小代币数量。 之间的区别$x_i$而最低要求正是可以保存的代币数量。 

这就把问题变成了每天一个简单的算术变换。

 | --- | --- | --- | --- |
 | 蛮力 |$O(\sum x_i)$|$O(1)$| 太慢了|

 ## 算法演练

 我们专注于一天$x$代币。 

1. 计算使用所有代币时可获得的最大金额。 这是$k = \left\lfloor \frac{a \cdot x}{b} \right\rfloor$。 该值代表当天可能的最佳整数奖励水平。 
2. 解释$k$向后：确定最小的令牌数$w$这样$\left\lfloor \frac{a \cdot w}{b} \right\rfloor = k$。 这确保我们达到相同的奖励水平而不会浪费代币。 
3. 解决不等式$$k \le \frac{a \cdot w}{b} < k+1$$重新排列为$$\frac{k \cdot b}{a} \le w < \frac{(k+1)\cdot b}{a}$$1.最小整数$w$满足这个是$$w_{\min} = \left\lceil \frac{k \cdot b}{a} \right\rceil$$1. 保存的代币数量很简单$x - w_{\min}$。 

每一天都是独立的，因此我们对所有输入重复此计算。 

### 为什么它有效

 关键的不变量是货币函数将整数线划分为连续的区间，其中区间中的每个值都会产生相同的奖励。 在每个间隔内，花费更多代币并不会改善结果。 因此，最优策略总是选择约束下可获得的最大奖励对应的区间的左边界$w \le x$。 这保证了最大程度的节省，因为任何更大的$w$不会增加奖励，并且任何较小的奖励$w$会减少它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    xs = list(map(int, input().split()))
    
    for x in xs:
        k = (a * x) // b
        w_min = (k * b + a - 1) // a
        print(x - w_min, end=' ')
        
solve()
```该解决方案计算可实现的最佳奖励水平$k$使用所有令牌。 然后，它使用上限除法技巧重建达到相同奖励所需的最小代币数量：$(k \cdot b + a - 1) // a$。 从中减去这个$x$给出了在不减少资金的情况下可以安全保存的最大代币数量。 

必须小心整数运算。 乘法$a \cdot x$可以达到$10^{18}$，但 Python 可以安全地处理它。 上限划分必须仔细实施，以避免相差一的错误。

 ## 边缘情况

 当$x_i$非常小，比如$x_i = 1$，计算出的奖励水平$k$变为零。 在这种情况下，最小$w$获得相同奖励的代币也为零，因此可以保存所有代币。 该算法正确地处理了这个问题，因为$k = 0$导致$w_{\min} = 0$，产生充分的节省。 

什么时候$x_i$很大并且接近边界，其中增加$w$没有改变$\left\lfloor \frac{a w}{b} \right\rfloor$，计算出的$w_{\min}$崩溃到最近的阈值。 例如，如果$a=1, b=4, x=6$， 然后$k=1$， 和$w_{\min}=4$。 算法正确保存$2$代币，符合支出超出的事实$4$不会产生额外的好处。 

什么时候$a$和$b$相等，则函数变为$k = x$， 和$w_{\min} = x$，因此不会保存任何令牌。 该算法自然会减少到零节省，因为每个代币恰好贡献一个单位的奖励。
