 ## 解决方案
 ## 问题理解

 每张邮票描述了两个城市之间的直接换乘。 如果信封包含`n`邮票，然后这封信准确无误地通过了`n + 1`城市按顺序排列。 该路线不会重访城市，因此整个旅程形成一条简单的路径。 

邮票是无序的。 我们只知道哪些城市在交付过程中是连续的。 我们的任务是重建路线中所有城市的有效排序。 

这自然是一个图问题。 每个城市都是一个顶点，每个印记都是一条无向边，最终的图保证是一条简单的路径。 一条路径与`n`边总是恰好有两个度数顶点`1`，端点，而每个内部顶点都有度数`2`。 

约束足够大，无法进行强力排列检查。 和`n`最多`10^5`，解必须接近线性时间。 任何重复扫描图或尝试多个候选路线的方法很快就会变得太慢。 一个`O(n)`或者`O(n log n)`解决方案是完全安全的。 

有一些简单的错误会默默地破坏重建。 

一个常见的错误是从任意节点而不是端点开始遍历。 考虑：```
3
1 2
2 3
3 4
```如果我们从`2`，我们可以移动到`1`然后被困住了，错过了一半的路线。 正确的遍历必须从度开始`1`节点，或者`1`或者`4`。 

另一个微妙的问题是假设城市标签是小整数。 该问题允许值高达`10^9`。```
2
1000000000 7
7 42
```使用按城市编号索引的数组会浪费大量内存或完全崩溃。 需要哈希映射。 

第三个错误是忘记了图是无向的。 例如：```
2
1 100
100 2
```有效路线是：```
1 100 2
2 100 1
```将印记视为有向边缘会错误地拒绝这些答案之一。 

## 方法

 蛮力的想法很简单。 我们可以尝试所有可能的城市排序，并检查连续对是否对应于邮票。 由于有`n + 1`城市，这需要检查`(n + 1)!`排列。 

即使是为了`n = 15`，这变得巨大。 为了`n = 10^5`，这是完全不可能的。 

稍微好一点的蛮力可以逐步构建路线。 选择一个起始城市，重复选择一个未使用的相邻边缘，并在路径无效时原路返回。 这是可行的，因为图被保证是一条路径，但如果不直接利用该结构，算法仍然会浪费时间探索不必要的状态。 

关键的观察结果是输入图已经是一个简单的路径。 每个内部城市恰好连接到两个邻居，并且只有两个端点分别连接到一个邻居。 

一旦我们确定了一个端点，重建就变得微不足道了。 从当前城市开始，我们最多可以移动到一个未访问过的邻居。 路线是强制的。 

这将问题转化为路径图上的简单图遍历。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O((n+1)!) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 为图构建邻接表。 

对于每一张邮票`(u, v)`， 添加`v`到邻居列表`u`，并添加`u`到邻居列表`v`。 
2. 找到路径的一个端点。 

在简单路径中，端点正是具有度数的顶点`1`。 我们扫描所有城市并选择邻接列表有大小的任何城市`1`。 
3. 从该端点开始遍历。 

将起始城市添加到答案中。 
4. 重复移动到下一个未访问过的邻居。 

由于该图是一条路径，因此每个内部节点恰好有两个邻居。 一个是我们来自的上一个城市，另一个是路线中的下一个城市。 
5. 跟踪上一个城市。 

每一步都检查当前城市的邻居。 搬到与之前城市不同的邻居。 
6. 当不存在进一步的移动时停止。 

这种情况发生在另一个端点，唯一的邻居是前一个城市。 

### 为什么它有效

 由邮票形成的图形保证是一条简单的路径。 简单路径只有两个端点且没有循环。 

从端点开始可以保证前进的每一步都是唯一确定的。 在任何内部顶点，一个相邻的城市是我们来自的城市，而另一个是路线上的下一个城市。 由于没有城市重复，因此选择未使用的邻居总是遵循原始路径。 

遍历对每个边恰好访问一次，对每个顶点也恰好访问一次，因此生成的序列是包含所有标记的有效路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    n = int(input())

    graph = defaultdict(list)

    for _ in range(n):
        u, v = map(int, input().split())
        graph[u].append(v)
        graph[v].append(u)

    start = -1

    for node in graph:
        if len(graph[node]) == 1:
            start = node
            break

    ans = []

    prev = None
    curr = start

    while True:
        ans.append(curr)

        next_node = None

        for nei in graph[curr]:
            if nei != prev:
                next_node = nei
                break

        if next_node is None:
            break

        prev, curr = curr, next_node

    print(*ans)

solve()
```邻接列表存储每个城市的所有邻近城市。 一个`defaultdict(list)`是理想的，因为城市标签可以大到`10^9`，所以我们不能直接按城市编号索引数组。 

起始节点的扫描依赖于路径图的定义属性：端点有度数`1`。 任一端点都是可接受的，因为反向路由也有效。 

遍历使用两个变量，`prev`和`curr`。 这避免了需要访问集。 由于每个节点最多有度数`2`，排除前一个城市立即识别正确的下一个城市。 

停止条件很微妙。 在最终端点，每个邻居都等于`prev`，所以没有有效的`next_node`存在。 在那一刻，路线就完成了。 

一个常见的实施错误是更新`prev`和`curr`以错误的顺序。 同时分配：```
prev, curr = curr, next_node
```保持两个值正确。

 ### 示例 1

 输入：```

```邻接表：```
1 -> [100]
100 -> [1, 2]

```端点是`1`和`2`。 假设我们从`1`。 

| 步骤| 上一页 | 当前| 下一个节点 | 回答 |

```该跟踪显示了为什么在选择端点后遍历变得确定。

```端点是`10`和`50`。 

| 步骤| 上一页 | 当前| 下一个节点 | 回答 |

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每条边和顶点都会被处理固定次数 |
 | 空间| O(n) | 邻接表存储所有边 |

 该图准确包含`n`边缘和`n + 1`顶点。 算法中的每个操作在图大小上都是线性的，这很容易符合`n = 10^5`。

 ## 边缘情况

 考虑遍历从中间开始而不是从端点开始的情况。 

输入：```
3
1 2
2 3
3 4
```图表是：```
1 - 2 - 3 - 4
```我们的算法首先扫描度数并找到`1`或者`4`。 假设它选择`1`。 

遍历：```
1 -> 2 -> 3 -> 4
```在每个内部节点，前一个城市被排除，只留下一个有效的下一个城市。 该算法永远不会过早陷入困境。 

现在考虑非常大的城市标识符。 

输入：```
2
1000000000 7
7 42
```邻接结构变为：```
1000000000 -> [7]
7 -> [1000000000, 42]
42 -> [7]
```由于该实现使用字典而不是索引数组，因此城市值本身不会影响内存使用。 

最后，考虑最小可能的有效路径。 

输入：```
1
8 9
```两个城市都有学位`1`。 从任一端点开始立即产生：```
8 9
```或者```
9 8
```遍历在一条边后正确停止，因为第二个城市没有剩余的未使用的邻居。
