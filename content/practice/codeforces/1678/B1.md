 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，并允许以单位成本翻转任何单个字符。 完成所有更改后，将通过将字符串压缩为相同字符的最大运行次数来解释该字符串。 游程只是相等位的连续块，我们关心这些游程的长度。 

当每个游程长度都是偶数时，字符串被认为是有效的。 这迫使结构非常严格：游程不能具有奇数大小，并且由于游程在 0 和 1 之间交替，因此整个字符串必须划分为交替的块，每个块具有偶数长度。 

任务是计算将输入字符串转换为满足此约束的任何字符串所需的最小翻转次数。 

所有测试用例的总长度最多为 2×10^5 的约束意味着我们每个测试用例需要一个线性或近线性的解决方案。 任何试图独立地重新计算每个位置的可能性或显式探索转换的方法都会太慢，因为即使跨测试的 O(n^2) 也是不可能的。 

一些边缘情况值得牢记。 

已经由偶数长度的游程组成的字符串已经有效，因此答案为零。 例如，“1100”是有效的，因为它变成长度为 2 和 2 的两个游程。 

仅当长度为偶数时，单次长游才有效。 “1111”有效，但“111”无效，修复它需要更改至少一个字符来破坏或调整奇偶校验。 

另一种微妙的情况是交替运行但只有一个边界“错误”。 例如，“1110011000”是无效的，尽管除了第一个和最后一个之外，许多运行都是偶数，这表明局部正确性并不意味着全局有效性。 

## 方法

 暴力方法会尝试考虑每个可能的长度为 n 的最终二进制字符串，计算其游程分解，并检查所有游程长度是否为偶数。 对于每个候选字符串，我们将计算其与输入的差异以计数翻转。 二进制字符串的数量是 2^n，甚至计算每个字符串也需要 O(n)，这使得这完全不可行。 

关键的观察是，条件“所有游程的长度均为偶数”相当于要求游程内的每一对相邻位置必须匹配，并且如果我们以结构化方式思考，则游程边界只能出现在偶数索引处。 我们可以强制执行配对结构，而不是考虑任意运行：位置 (1,2)、(3,4)、(5,6) 等必须表现一致。 

更具体地说，我们可以以两个字符的块来处理字符串。 如果我们希望每个运行具有偶数长度，则在每个有效的最终配置中，位置 i 和 i+1 必须属于同一运行，这意味着它们必须相等。 这将问题简化为决定每一对是否应变为“00”或“11”。 一旦我们修正了这种解释，每对的成本都是独立的，因为任何有效的最终字符串完全由每对的目标值的选择决定。 

因此，问题变成：对于每对 (s[2k], s[2k+1])，如果它们已经与我们选择的目标匹配，我们支付 0，否则我们为相对于所选对值的每个不匹配字符支付 1。 由于每一对独立地选择是全零还是全一，所以我们对每对采取更便宜的选择。 

这将全局运行奇偶校验约束转换为局部每对优化。

 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从左到右分两个位置处理字符串。

1. 将字符串拆分为连续的对 (s[i], s[i+1])。 这是有效的，因为 n 保证为偶数。 
2. 对于每一对，计算需要翻转多少次才能使其成为“00”以及需要翻转多少次才能使其成为“11”。 

第一个成本是该对中 1 的数量，第二个成本是该对中 0 的数量。 
3. 将这两个成本中较小的一个添加到答案中。 
4. 对所有对重复并输出累计总数。 

每个步骤的合理性在于，在任何有效的最终配置中，一对中的两个字符必须相同。 如果不是，游程将在该对内分裂，立即创建长度为 1 的游程，这是无效的，因为所有游程必须是偶数。 

### 为什么它有效

 关键属性是在任何有效的最终字符串中，索引 (2k−1, 2k) 必须属于同一运行。 如果它们处于不同的运行中，则其中一个运行将在该对内的奇数长度边界处开始或结束，从而在分解中的某处强制执行奇数运行。 

一旦我们接受每个有效解决方案都是通过选择每对值来完全确定的，成本就会分解为独立的子问题。 每对对翻转总数都有独立的贡献，并且任何跨对依赖性都不能改善结果，因为更改一对不会影响另一对的运行有效性。 

这种独立性保证了每对局部最优选择组合成全局最优解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input().strip())
    s = input().strip()

    ans = 0

    for i in range(0, n, 2):
        a = s[i]
        b = s[i + 1]

        ones = (a == '1') + (b == '1')
        zeros = 2 - ones

        ans += min(ones, zeros)

    print(ans)
```该解决方案依赖于迭代不相交的对，因此不需要额外的数据结构或状态跟踪。 唯一的微妙之处是确保索引的正确分组，因为移动一个位置将完全使配对逻辑失效。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()

        ans = 0
        for i in range(0, n, 2):
            a = s[i]
            b = s[i+1]
            ones = (a == '1') + (b == '1')
            ans += min(ones, 2 - ones)

        out.append(str(ans))

    return "\n".join(out)

 ## 边缘情况

 对于已经由统一对（例如“1100”）组成的字符串，算法会处理（11）和（00），两者都贡献零成本。 这与字符串已经分解为偶数长度的事实相匹配。 

对于像“101010”这样的完全交替的字符串，每一对都是混合的，因此每一对都只贡献一次翻转。 该算法产生三个，这对应于将每对独立地转换为全零或全一。 

对于像“01”这样的单个对，唯一有效的修复是翻转一位，并且算法正确地选择 min(1,1) = 1，这反映了任一方向的成本相同。 

这些案例证实，配对假设不会错过跨边界的相互作用，因为一对中的任何修正都不会影响另一对的可行性。
