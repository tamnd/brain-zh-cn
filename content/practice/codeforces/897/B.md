 ## 解决方案
 ## 问题理解

 我们被要求按升序列出特殊数字并取前缀和。 

如果一个数的十进制正反读相同且长度为偶数，则认为该数有效。 这意味着每个有效数字完全由其前半部分决定，因为后半部分只是前半部分的镜像。 然后我们取最小的有效数，将其中最小的 k 相加，最后输出模 p 的总和。 

输入给出 k（我们需要的最小回文数）和 p（应用于最终总和的模数）。 任务不是找到单个回文或检查成员资格，而是生成所有偶数长度回文的有序序列并聚合前 k 项。 

约束 k 高达 100000 会显着改变问题结构。 检查每个整数并测试它是否是回文的直接方法会太慢，因为随着数字的增长，回文会变得稀疏，并且扫描整数直到第 k 个有效的整数很容易超过数十亿次检查。 相反，我们必须直接利用回文的构造。 

一个微妙的陷阱是假设回文应该通过暴力枚举按数字顺序生成。 但这会失败，因为大多数整数都不是回文，并且跳过无效数字仍然会花费与搜索空间成比例的时间。 另一个问题是意外地包含了像 12321 这样的奇数长度回文，尽管它们是回文，但它们显然是无效的。 第三个常见错误是忘记不允许使用前导零，这会影响我们如何解释“一半”表示。 

## 方法

 一种简单的方法会迭代从 1 开始的所有整数，检查每个整数是否是回文，检查其数字长度是否为偶数，并收集满足这两个条件的整数，直到找到 k。 这是正确的，但效率极低。 在最坏的情况下，要找到 100000 个有效的偶数长度回文，我们需要扫描远远超过 10^9 的整数，因为随着数字的增长，有效回文会变得越来越不频繁。 每次回文检查的成本为 O(d)，其中 d 是位数，因此总复杂度变得难以接受。 

关键的观察是每个偶数长度回文都由其前半部分唯一确定。 如果我们选择一个数字 x，我们可以通过将 x 的倒数附加到其自身来构造一个回文。 这将问题转化为生成所有按其半表示的数字长度分组的正整数。 

排序也是结构化的。 首先是所有 2 位数回文数，然后是所有 4 位数回文数，然后是 6 位数回文数，依此类推。 在固定长度的组中，回文的排序遵循其前半部分的自然排序。 

这使我们能够直接逐层构建序列，而无需检查非回文。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力枚举| O(N·d) | O(1) | O(1) | 太慢了|
 | 从半数构造 | O(k·d) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 我们从一位数的一半开始向上迭代可能的半长。 每个半长m对应于长度为2m的回文。 这种排序是必要的，因为较小的长度总是产生较小的数字。 
2.对于每个半长m，我们按升序生成所有有效的半数。 对于 m = 1，这是 1 到 9。对于 m ≥ 2，这是从 10^(m−1) 到 10^m − 1。这确保构造的回文中不会出现前导零。 
3. 对于每个半数，我们通过将该数字与其十进制形式的倒数连接起来构造完整的偶数长度回文。 这保证了回文性质的正确性。 
4. 我们维护生成的回文的运行列表（或运行总和）。 每次我们生成一个回文时，我们都会将其添加到模 p 的和中。 
5. 一旦生成了 k 个回文，我们就立即停止。 一旦满足要求，就无需生成进一步的长度。 

正确性背后的核心思想是，这个生成过程仅枚举每个有效的偶数长度回文一次，并且严格按照递增顺序。 

### 为什么它有效

 每个有效数均由其前半部分唯一确定，因此长度 2m 的有效回文与 [10^(m−1), 10^m − 1] 范围内的整数（或 [1, 9]，m = 1）之间存在双射。 由于这些范围以 m 的递增顺序遍历，并且在每个范围内以递增的数字顺序遍历，因此结果序列是全局排序的。 这保证了采用该构造的前 k 个元素相当于采用 k 个最小的有效回文。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def make_pal(x: int) -> int:
    s = str(x)
    return int(s + s[::-1])

k, p = map(int, input().split())

res = 0
cnt = 0
m = 1

while cnt < k:
    if m == 1:
        start, end = 1, 9
    else:
        start = 10 ** (m - 1)
        end = 10 ** m - 1

    x = start
    while x <= end and cnt < k:
        pal = make_pal(x)
        res = (res + pal) % p
        cnt += 1
        x += 1

    m += 1

print(res)
```该解决方案直接从其半表示构造回文。 辅助函数通过字符串反转将数字转换为其偶数长度回文，这在这里是安全的，因为 k 最多为 100000，因此总的字符串操作仍然很小。 

外循环控制一半的数字长度。 内部循环枚举该长度的所有有效一半。 提前停止条件确保一旦收集到 k，我们就不会生成不必要的回文。 

一个常见的实现错误是忘记分离 m = 1 的情况，其中前半部分不能从 0 开始。另一个微妙的问题是整数溢出，但 Python 天生可以处理大整数，并且模数减少可以防止无限增长。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(k·d) | 每个回文都由半数构建并反转一次，数字长度 d ≤ 5（对于 k ≤ 1e5）|
 | 空间| O(1) | O(1) | 仅存储计数器和运行总和 |

 约束允许直接构造，因为 k 只有 100000，并且每次操作都很便宜。 即使存在字符串反转开销，总工作量仍保持在限制范围内。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def make_pal(x: int) -> int:
        s = str(x)
        return int(s + s[::-1])

    k, p = map(int, input().split())
    res = 0
    cnt = 0
    m = 1

    while cnt < k:
        if m == 1:
            start, end = 1, 9
        else:
            start = 10 ** (m - 1)
            end = 10 ** m - 1

        x = start
        while x <= end and cnt < k:
            res = (res + make_pal(x)) % p
            cnt += 1
            x += 1
        m += 1

    return str(res)

 ## 边缘情况

 一个关键的边缘情况是 k 足够小，只需要 1 位半数。 对于像 k = 1 这样的输入，算法根本不能尝试生成更高的数字长度。 循环结构自然会处理这个问题，因为一旦 cnt 达到 k，它就会立即停止。 

另一种边缘情况是当 k 跨越多个数字长度层时。 例如，k = 10 强制算法耗尽所有 1 位数的一半（9 个值），然后开始 2 位数的一半。 分层结构可确保跨此边界的排序保持正确，因为所有 1 位数回文都严格小于所有 4 位数回文。 

最后，模 p = 1 是退化的，因为所有输出都变为零。 正在运行的模更新无需特殊外壳即可安全地处理此问题。
