 **已验证：** 否

 ## 解决方案
 ## 问题理解

 每个车厢都有自己的最大速度。 当所有车厢开始移动时，任何车厢的移动速度都不能比它前面的任何车厢快，因此它的实际速度成为从左边看到的最小值。 

如果最大速度是```
a = [10, 13, 5, 2, 6]
```那么最终的速度是```
[10, 10, 5, 2, 2]
```因为每节车厢都被前面最慢的一节车厢所限制。 

火车是最终速度相等的最大连续段。 在上面的例子中，火车是```
[10,10] [5] [2,2]
```所以答案是3。 

之后，我们会收到更新。 更新会减少数组的一个元素。 每次更新后，我们必须报告新的列车数量。 

关键的观察是运输的最终速度`i`是```
min(a[1], a[2], ..., a[i])
```当这个前缀最小值减小时，新的列车正好开始。 

这意味着列车的数量等于创建新前缀最小值的位置数量。 

约束足够大，以至于在每次更新后重新计算所有前缀最小值是不可能的。 在所有测试用例中，`n`和`m`总和为`10^5`，所以我们需要一些东西`O((n + m) log n)`。 任何在每次更新后扫描整个数组的解决方案都会执行大约`10^10`最坏情况下的操作。 

一个微妙的点是更新只会减少值。 没有任何东西会增加。 这种单调性使得高效的动态结构成为可能。 

考虑：```
a = [5, 8, 6]
```火车的出发位置是：```
1 (value 5)
```现在减少`a[2]`到`4`。```
a = [5, 4, 6]
```位置 2 成为新的列车起点，因为它比之前的每个值都小。 

如果粗心的解决方案只更新索引 2 处的信息，就会忽略右侧更远的列车边界可能会消失的事实。 

另一个棘手的情况是平等：```
a = [5, 5, 5]
```只有一趟火车。 

仅当位置值**严格小于**所有先前的前缀最小值时，位置才会创建新的序列。 使用`<=`而不是`<`会错误地数出三列火车。 

## 方法

 暴力解法直接遵循定义。 

每次更新后，重建​​前缀最小值数组。 每当前缀最小值减少时，新的列车就会开始。 计算这些减少就可以得出答案。 

这是正确的，因为每个车厢的最终速度恰好是其前缀最小值。 不幸的是，重建前缀最低成本`O(n)`每个查询，导致`O(nm)`整体工作。 两个值都在附近`10^5`，这太慢了。 

关键的观察是我们实际上并不关心每节车厢。 我们只关心创建新前缀最小值的位置。 

我们将此类职位称为**领导者**。 

例如：```
a = [10, 13, 5, 2, 6]
```领导者是：```
1 (10)
3 (5)
4 (2)
```领导者的数量恰好是列车的数量。 

现在看看减少后会发生什么。 

假设位置`k`变小。 只有两件事可能发生。 

第一的，`k`如果其价值低于前任领导者的价值，则可能成为新的领导者。 

第二次、一次`k`成为领导者（或者现有领导者变得更小），其右侧的一些领导者可能不再是领导者，因为新的前缀最小值更早到达他们。 

领导者自然是按职位排序的，其价值观是严格递减的。 这使我们能够通过向右行走来删除受影响的领导者，直到遇到具有较小值的领导者。 

我们动态地维护当前的领导者群体。 有序结构让我们可以找到前一个和下一个领导者`O(log n)`时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(纳米) | O(n) | 太慢了|
 | 最佳| O((n + m) log n) 摊销 | O(n) | 已接受 |

 ## 算法演练

 1. 建立第一批领导者。 

从左到右扫描，同时保持迄今为止看到的最小值。 位置`i`成为领导者，如果`a[i]`严格小于该最小值。 
2. 将领导者存储在有序结构中。 

我们需要在任何位置之前或之后快速找到领导者。 领导职位上的 Fenwick 树提供了此功能。 
3. 处理更新`(k, d)`。 

减少`a[k]`经过`d`。 
4.找到之前的前任领导者`k`。 

如果没有前任领导者，那么`k = 1`实际上没有来自左翼的限制。 
5. 检查是否`k`应该是一个领导者。 

位置`k`正是当```
a[k] < value_of_previous_leader
```或者当它是第一个位置时。 
6. 如果`k`成为领导者但还不是领导者，将其插入领导者结构中。 
7. 如果`k`当前是领导者，删除其右侧无效的领导者。 

之后反复看下一个领导`k`。 

而其值大于或等于`a[k]`，它无法再创建新的前缀最小值，因此将其删除。 

一旦到达具有较小值的领导者就停止。 
8.当前的领导者数量是本次更新后的答案。 

### 为什么它有效

 领导者正是前缀最小值减少的位置。 由于列车边界恰好出现在前缀最小值的递减处，因此领导者和列车是同一对象。 

领导者集合始终具有严格递减的值。 当位置上有一个值时`k`减少，仅从以下位置开始的前缀最小值`k`可以改变。 之前的职位`k`不受影响。 

如果`a[k]`变得小于之前的领导者值，`k`必须成为新的领导者。 任何后来的领导者，其价值不小于`a[k]`不能再代表前缀最小值的减少，因此必须将其删除。 第一个具有较小值的领导者仍然有效，并且其后的每个领导者也保持有效，因为领导者值严格递减。 

因此，维护的领导集始终恰好是前缀最小位置的集合，因此其大小始终是列车的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, idx, delta):
        n = self.n
        bit = self.bit
        while idx <= n:
            bit[idx] += delta
            idx += idx & -idx

    def sum(self, idx):
        bit = self.bit
        res = 0
        while idx > 0:
            res += bit[idx]
            idx -= idx & -idx
        return res

    def kth(self, k):
        idx = 0
        bitmask = 1 << (self.n.bit_length() - 1)

        while bitmask:
            nxt = idx + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                idx = nxt
            bitmask >>= 1

        return idx + 1

def solve():
    t = int(input())

    for _ in range(t):
        line = input()
        while line.strip() == "":
            line = input()

        n, m = map(int, line.split())
        a = [0] + list(map(int, input().split()))

        fw = Fenwick(n)
        leader = [False] * (n + 1)

        cur_min = 10**18
        trains = 0

        for i in range(1, n + 1):
            if a[i] < cur_min:
                cur_min = a[i]
                leader[i] = True
                fw.add(i, 1)
                trains += 1

        def next_leader(pos):
            cnt = fw.sum(pos)
            if cnt >= trains:
                return 0
            return fw.kth(cnt + 1)

        ans = []

        for _ in range(m):
            k, d = map(int, input().split())
            a[k] -= d

            cnt_before = fw.sum(k - 1)

            if cnt_before == 0:
                should_be_leader = True
            else:
                prev_leader = fw.kth(cnt_before)
                should_be_leader = a[k] < a[prev_leader]

            if should_be_leader and not leader[k]:
                leader[k] = True
                fw.add(k, 1)
                trains += 1

            if leader[k]:
                nxt = next_leader(k)

                while nxt and a[nxt] >= a[k]:
                    leader[nxt] = False
                    fw.add(nxt, -1)
                    trains -= 1
                    nxt = next_leader(k)

            ans.append(str(trains))

        print(" ".join(ans))

if __name__ == "__main__":
    solve()
```芬威克树储存了`1`在每一个领导岗位上`0`别处。 这使我们能够在领导者中找到前任和继任者，而无需存储平衡的 BST。 

这`kth()`方法是标准的 Fenwick 订单统计操作。 给定一个等级，它会返回该领导者的位置。 

更新逻辑反映了证明。 首先我们决定是否`k`成为领导者。 那么，如果`k`是一个领导者，我们反复删除其右侧的主导领导者。 

一个常见的错误是使用`<=`在决定一个职位是否成为领导者时。 相等的值不会创建新的前缀最小值，因此条件必须严格遵守`<`。 

另一个容易犯的错误是用以下方式删除领导者：`>`而不是`>=`。 如果两位领导者的价值观相同，那么后一位就不是真正的前缀最小职位，必须消失。
