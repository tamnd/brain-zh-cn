 ## 解决方案
 ## 问题理解

 我们得到一个仅由两个符号组成的字符串，其中一个在类似 OR 的合并操作下表现得像中性值，另一个表现得像吸收“真”值。 该操作允许我们选择两个相邻的字符，删除它们，并用逻辑或替换它们：如果其中一个字符是 Y，则结果是 Y，否则结果是 N。每个操作都会将字符串缩短一个字符，并且我们不断重复此操作，直到只剩下一个字符。 

限制是我们在任何时候都不允许直接合并两个 Y 字符。 即使它通常仍会产生 Y，该移动也是被禁止的。任务是确定是否存在某种合并序列，可以将字符串减少为单个字符，而无需选择 YY 对。 

约束很小：每个字符串的长度最多为 100，并且最多有 500 个测试用例。 这立即排除了对大状态进行复杂动态编程或对所有合并顺序进行搜索的任何需要。 理论上，即使在 n = 100 时，所有合并序列的指数探索也是可以想象的，但是禁止 YY 合并的附加约束对结构进行了足够严重的修剪，以至于可以预期直接组合表征。 

一个关键的微妙之处是合并会改变邻接关系。 天真的解释可能假设我们可以只计算 Y 和 N，但邻接性很重要，因为 Y 在删除后可以成为邻居。 另一个微妙的陷阱是认为避免 YY 合并意味着 Y 必须永远保持分离，这是不正确的，因为 Y 可以间接“通过”N 次合并。 

例如，在`YNY`, 可以合并`NY -> Y`给予`YY`，如果我们稍后必须直接合并它们，这已经无效了。 但在某些配置中，即使存在多个 Y，仔细的排序也可以避免直接合并两个 Y。 

因此，真正的问题是我们是否可以安排合并，以便在合并时没有任何步骤会产生 YY 邻接。 

## 方法

 蛮力的想法是通过重复选择相邻对进行合并来模拟减少字符串的所有可能方法，同时跟踪是否曾经使用过 YY 合并。 这形成了一个状态空间，其中每个状态都是一个字符串，并且转换对应于合并任何相邻对。 可能的合并序列的数量是巨大的，因为长度为 n 的字符串最初大约有 n 个选择，然后是 n−1，依此类推，导致阶乘增长。 尽管 n 只有 100，但这对于探索来说太大了。 

关键的观察是我们实际上并不关心中间字符串的全部细节。 唯一危险的事件是当我们决定合并两个 Y 时它们变得相邻。 这表明 Y 的行为就像障碍物一样，在它们可能成为邻居的每个阶段都必须至少间隔一个 N。 

现在看看 N 做了什么。 合并任何涉及 N 的东西往往会移除 N 或将其“吸收”到 Y 中。这意味着 N 不是稳定的障碍。 然而，出现了一个关键的结构简化：如果字符串中至少有两个 Y，那么在任何归约过程中的某个时刻，这些 Y 将不可避免地在任何最终的单字符归约中变得相邻，除非在整个过程中至少有一个 N 将它们分开。 但 N 会被消耗，因此它们无法永久分隔多个 Y。 

这导致了强烈的二分法：如果有两个或多个 Y，答案通常是否定的，除非结构允许我们折叠所有内容而不需要 YY 合并。 当至少有两个 Y 时，这是不可能的，因为任何将长度减少到 1 的收缩过程最终都必须跨越迫使 Y 相邻的边界合并。 

唯一幸存的安全案例是：

 当没有 Y 时，或者恰好有一个 Y 且周围有 N 排列，使得 Y 在收缩过程中永远不会遇到另一个 Y。 事实上，这进一步简化为一个干净的条件：字符串有效当且仅当它最多包含一个 Y。 

我们可以通过检查来证明这一点：

 如果 Y 为零，则每次合并都是 NN → N，因此字符串始终保持全 N，并且可以简单地简化。 

如果恰好有一个 Y，则每次涉及它与 N 的合并都会产生 Y，并且由于不存在第二个 Y，因此不会发生禁止的 YY 合并。 

如果有两个或多个 Y，则任何对单个字符的缩减都需要最终组合包含 Y 的区域，这会在任何合并序列中的某个步骤强制 YY 邻接。 

所以问题就简化为一个简单的计数条件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 所有合并订单的暴力模拟 | O(n!) | O(n) | 太慢了 |
 | 计算 Y 并检查是否 ≤ 1 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 ## 算法演练

 1. 对于每个测试用例，扫描字符串并计算有多少个字符等于 Y。这将捕获与是否可以强制禁止合并相关的所有信息。 
2. 如果Y的计数为零，则立即输出YES。 任何操作都无法创建 Y，因此该字符串表现为 N 值的纯粹折叠序列。 
3. 如果Y的计数恰好为1，则输出YES。 涉及单个 Y 的任何合并永远不会涉及另一个 Y，因此永远不会触发禁止的操作。 
4. 如果Y的计数为2或更多，则输出NO。 在存在多个 Y 的情况下，任何完全减少为单个字符都必然会使 Y 在某个中间阶段相邻，从而不可避免地发生禁止合并。 

### 为什么它有效

在操作过程中产生 Y 的唯一方法是通过与至少一个 Y 合并。一旦存在多个 Y，每个缩减步骤都会保留或减少它们的数量，但不能将它们分离成永久隔离的组件，因为合并消除了边界。 由于该过程必须将字符串缩减为单个字符，因此所有区域最终都会交互。 这保证了两个 Y 原点区域变得相邻并且需要直接合并的阶段，这违反了约束。 当 Y 最多为 1 个时，Y 源区域之间不存在这种相互作用，因此该过程始终可以安全地进行。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    y_count = s.count('Y')
    if y_count <= 1:
        print("YES")
    else:
        print("NO")
```该实现直接应用了仅 Y 字符数量重要的观察结果。 这`.count()`操作每个测试用例扫描一次字符串，这在给定约束的情况下就足够了。 

唯一微妙的一点是确保我们统一对待所有情况：空 N 主导字符串和单 Y 字符串都被接受，而任何更多数量的 Y 都会被拒绝。

 我们追踪两个有代表性的案例。

 这表明单个 Y 永远不会强制与另一个 Y 交互，并且所有合并每次操作始终最多涉及一个 Y。 

### 示例 2：`YYNY`| 步骤| 字符串| Y 计数 | 观察|
 | --- | --- | --- | --- |
 | 0 | YYNY | 3 | 多个 Y 存在 |

 此案例表明，在任何完全归约过程中，多个 Y 区域不可避免地会崩溃为邻接，从而强制进行禁止的合并。 

这里说明的不变量是 Y 原点分量的数量不能通过完全减少到长度 1 来保持隔离。

import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    t = int(input())

        print("YES" if s.count('Y') <= 1 else "NO")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    sys.stdin = old_stdin
    return out.getvalue().strip()

 ## 边缘情况

 任何位置的单个 Y 的行为始终相同，因为与 N 合并不会创建新的 Y 交互。 例如，在`NYNN`，每个有效的合并序列最多保持一个 Y 处于活动状态，因此该过程始终可以安全地进行到单个字符，而无需形成 YY 邻接。 

像这样的字符串`YNNY`暴露了仅基于邻接的朴素推理的失败模式。 尽管 Y 最初是分开的，但任何减少长度的合并序列最终都会迫使它们的区域之间发生相互作用。 此时，两个 Y 派生组件必须相遇，这将需要禁止的 YY 合并。 这正是计算 Y 就足够的原因：收缩时分离不会保留。
