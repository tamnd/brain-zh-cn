[CF 219B - 特别优惠！ 超级价格999布尔！](https://codeforces.com/problemset/problem/219/B)

 **标签：** 实施

 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 Polycarpus 已经知道他的产品的最佳正常价格，`p`。 他最多愿意减少`d`布尔斯，如果这能给最终价格一个更有吸引力的结局，特别是尽可能多的尾随九。 

尾随九表示数字`9`在号码的末尾。 例如，`12999`后面有三个 9，而`9099`有两个，因为只有后缀很重要。 

在所有价格中`x`这样：

 -`x <= p`-`p - x <= d`我们想要的是后面 9 个数最多的那个。 如果几个价格的尾随 9 的数量相同，我们会选择最大的价格。 

限制是这里有趣的部分。`p`可以大到`10^18`，所以我们不能迭代区间内的每个可能的价格`[p-d, p]`。 在最坏的情况下，该区间本身几乎可以包含`10^18`数量，远远超出了一秒的时间限制。 

问题的结构表明只有非常具体的候选人才重要。 以 1 尾随 9 结尾的数字如下所示：```
...9
```以两个尾随 9 结尾的数字如下所示：```
...99
```以三个 9 结尾的数字如下所示：```
...999
```等等。 

对于每一个可能的尾随 9 的计数，恰好有一个最大的候选者不超过`p`。 这种观察使问题变得很小。 

有一些边缘情况很容易被错误处理。 

认为：```
p = 1000
d = 0
```我们根本不允许降低价格。 答案必须留下来`1000`， 虽然`999`有更多的尾随九。 总是向下舍入到最接近的粗心实现`999...`值将错误输出`999`。 

另一个棘手的情况是：```
p = 10999
d = 1
```答案是`10999`因为它已经有三个尾随的 9。 即使最佳答案已经等于，某些实现也会不必要地修改数字`p`。 

一个更微妙的情况是：```
p = 10000
d = 100
```最好的答案是`9999`。 它有四个尾随 9，并且仅花费`1`布尔小于`p`。 如果我们贪婪地尝试首先最大化价值，我们可能会错误地停在`9990`或者`999`。 

最后一个重要的细节是决胜局。 考虑：```
p = 1999
d = 1000
```两个都`999`和`1999`是有效的。 每个都有三个尾随的 9。 我们必须选择较大的一个，即`1999`。 

## 方法

 蛮力的想法很简单。 迭代每个候选价格`x`从`p-d`最多`p`，统计每个数字有多少个尾随9，并根据规则保留最好的一个。 

计算后面的 9 很容易。 反复检查最后一位数字是否为`9`, 除以`10`，并计算成功的次数。 

蛮力法是正确的，因为它会检查每个有效价格。 问题在于搜索空间的大小。 如果`p = 10^18`和`d`也很大，我们可能需要检查近`10^18`数字。 即使对每个数字执行一次操作也是不可能的。 

关键的观察结果是，带有许多尾随 9 的数字是非常结构化的。 

对于固定数量的尾随 9`k`，最大数量不超过`p`替换最后一个得到`k`数字与`9`。 

例如，如果：```
p = 543210
```那么：

 - 尾随 9 的最大数字是`543209`- 后面有两个 9 的最大数字是`543199`- 具有三个尾随 9 的最大数字是`542999`没有必要检查任何具有相同数量的尾随 9 的较小候选者，因为该问题要求并列之间的最大价格。 

这极大地减少了搜索空间。 我们只需要尝试每个可能的后缀长度即可。 自从`p <= 10^18`，最多有 19 位数字，因此仅存在大约 19 个候选。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(d log p) | O(d log p) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(log p) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从当前最佳答案开始等于`p`。 

这处理了降低价格没有好处或不允许的情况。 
2. 对于每10的次方`10^k`,构造最大不超过的数`p`谁的最后`k`数字都是`9`。 

我们可以将其计算为：```
candidate = (p // 10^k) * 10^k - 1
```该部门删除了最后一个`k`数字，乘法将它们恢复为零，减一将这些零变成九。 
3. 检查候选人是否有效。 

候选人必须满足：```
p - candidate <= d
```否则所需的折扣太大。 
4. 将候选答案与当前最佳答案进行比较。 

如果候选者有更多的尾随 9，则优先选择该候选者。 如果两者尾随 9 的数量相同，则选择较大的数字。 

在实践中，迭代`k`从小到大已经保证了后来的有效候选者至少有同样多的尾随 9。 
5. 继续`10^k <= p * 10`。 

自从`p`最多有 19 位数字，这个循环只运行几次。 
6. 打印最佳答案。 

### 为什么它有效

 对于任意固定数量的尾随 9`k`，具有该属性的每个有效数字都可以写为：```
some_prefix * 10^k + (10^k - 1)
```在所有这些数字中不超过`p`，最大的正是：```
(p // 10^k) * 10^k - 1
```如果这个最大的候选者因为需要太大的折扣而无效，那么每个较小的数字都具有相同的`k`落后的九号距离更远`p`，所以它们都不能工作。 

这意味着仅测试每个的最大候选者`k`就足够了。 

由于我们检查了尾随 9 的所有可能计数，并且对于每个计数我们测试了可能的最佳数字，因此算法不会错过最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def trailing_nines(x):
    cnt = 0
    while x % 10 == 9:
        cnt += 1
        x //= 10
    return cnt

def solve():
    p, d = map(int, input().split())

    ans = p
    best = trailing_nines(p)

    power = 10

    while power <= 10**19:
        candidate = (p // power) * power - 1

        if candidate >= 0 and p - candidate <= d:
            cur = trailing_nines(candidate)

            if cur > best or (cur == best and candidate > ans):
                best = cur
                ans = candidate

        power *= 10

    print(ans)

solve()
```辅助函数通过重复检查最后一位数字来计算尾随的 9。 由于数字最多有 19 位数字，因此该操作实际上是常数时间。 

主循环迭代十的幂。 对于每个幂，它都会构建最大可能的候选者，并以所需数量的 9 结尾。 

表达式：```
(p // power) * power - 1
```是解决方案的关键部分。 

认为：```
p = 543210
power = 1000
```然后：```
p // power = 543
543 * 1000 = 543000
543000 - 1 = 542999
```这正是不超过的最大数字`p`后面有三个 9。 

条件：```
p - candidate <= d
```过滤掉需要太多折扣的候选人。 

平局决胜规则是明确实施的。 如果两个候选人的尾随 9 数量相同，我们保留较大的那个。 

循环上限`10**19`安全地覆盖每个可能的数字长度`p <= 10^18`。

import io

def solve():
    input = sys.stdin.readline

    def trailing_nines(x):
        cnt = 0
        while x % 10 == 9:
            cnt += 1
            x //= 10
        return cnt

                best = cur
                ans = candidate

        power *= 10

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    out = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = old_stdout
    return out.getvalue().strip()

# provided sample
assert run("1029 102\n") == "999", "sample 1"

# minimum case
assert run("1 0\n") == "1", "minimum values"

# already optimal

# small decrease unlocks many nines

 ## 边缘情况

 考虑输入：```
1000 0
```该算法开始于`ans = 1000`。 候选人`999`生成时`power = 10`， 但：```
1000 - 999 = 1
```这超过了`d = 0`。 

所以候选人被拒绝了，答案仍然存在`1000`。 

现在考虑：```
10999 1
```最初的答案已经有三个 9。 

什么时候`power = 10`，候选人变为：```
10999
```因为：```
(10999 // 10) * 10 - 1 = 10999
```该算法正确地保留了原始值。 

为了：```
10000 100
```第一个候选人是：```
9999
```有折扣`1`。 

这立即给出了四个尾随的 9，这是最佳的。 更大的力量仍在生产`9999`，所以答案永远不会改变。 

最后，考虑一下打破平局的例子：```
1999 1000
```两个都`1999`和`999`拥有三个尾随的 9。 

该算法开始于`ans = 1999`。 稍后可能会生成`999`，但由于两者具有相同的后缀数并且`1999 > 999`，存储的答案不会改变。
