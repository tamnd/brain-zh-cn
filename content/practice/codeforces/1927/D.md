 ## 解决方案
 ## 问题理解

 该问题为您提供了一个整数数组和一系列查询，每个查询指定该数组的一个段。 对于每个查询，系统会要求您在段内查找两个位置，使得这些位置处的值不同。 如果该段中的所有数字都相等，则必须报告不存在这样的对。 输出只是有效对的索引或`-1 -1`如果不存在。 

这里的关键是理解我们不需要特定的值本身，只需要它们相对于彼此的位置。 约束表明数组最多可以有 200,000 个元素，并且最多可以有 200,000 个查询。 这立即排除了任何检查每个查询范围内的每一对的解决方案，因为这可能会导致粗略的结果$10^{10}$在最坏的情况下，操作速度太慢了。 

当段中的所有数字都相同时，就会出现边缘情况。 一个简单的方法可能总是返回前两个索引，但是在像这样的段中`[7, 7, 7]`，这是不正确的。 另一个微妙的边缘情况是长度为 2 且编号相同的段； 正确的输出仍然是`-1 -1`。 由于查询中基于 1 的索引，粗心的实现还会带来差一错误的风险。 

## 方法

 强力解决方案将迭代每个查询并比较段内的每对元素。 对于长度查询$m$，这需要$O(m^2)$运营。 这种方法原则上是正确的，因为它详尽地检查了所有可能的对，但是当$m$量大，查询量高。 

最佳解决方案利用了这样的观察：要找到一对不同的元素，只需知道第一个位置和具有不同值的位置即可。 对于每个查询，最简单的策略是将第一个元素固定为候选，从第二个元素扫描到段的末尾，一旦发现不同的值就停止。 这保证了最早的有效对，而无需扫描整个段。 由于每个查询都是独立处理的，并且扫描提前停止，因此总体复杂度与所有查询段的总长度成正比，这在给定的约束下是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(q * n^2) | O(q * n^2) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(所有查询段长度的总和) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 
2. 对于每个测试用例，读取数组大小`n`和数组元素`a`。 
3.读取查询数量`q`。 
4. 对于每个查询，读取边界`l`和`r`。 由于查询是从 1 开始的，因此在对数组进行索引时请记住这一点。 
5. 存储段中第一个元素的值，`first_value = a[l-1]`。 
6.从索引扫描`l`到`r`并将每个元素与`first_value`。 
7. 如果在索引处发现不同的元素`j`，输出索引`(l, j+1)`并停止扫描。 
8. 如果扫描完成后没有找到不同的元素，则输出`-1 -1`。 

为什么它有效：不变的是从左侧扫描保证第一个元素始终是`a[l]`，并且任何有效对都必须包含此元素。 一旦找到不同的值，它就会形成一个有效的对。 如果不存在这样的元素，则整个段包含相同的数字，唯一正确的输出是`-1 -1`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        q = int(input())
        for _ in range(q):
            l, r = map(int, input().split())
            first_value = a[l - 1]
            found = False
            for j in range(l, r):
                if a[j] != first_value:
                    print(l, j + 1)
                    found = True
                    break
            if not found:
                print(-1, -1)

if __name__ == "__main__":
    solve()
```该解决方案首先使用快速 I/O 读取输入。 对于每个查询，它立即将第一个元素与后续元素进行比较，直到发现差异。 如果不存在差异，则输出`-1 -1`。 使用基于 1 的输出索引对于匹配问题规范至关重要。 Break 语句确保我们在找到有效对后立即停止扫描，从而防止不必要的操作。 

## 工作示例

 ### 示例 1

 输入段：`[1, 1, 2, 1, 1]`， 询问`(1,5)`| j（扫描索引）| 一个[j] | 与 a[0] | 比较 行动|
 | ---| ---| ---| ---|
 | 1 | 1 | 1 == 1 | 1 == 1 继续 |
 | 2 | 2 | 2！= 1 | 输出1 3，停止|

 第一个元素在索引 3 处不同，产生有效对`(1,3)`。 

### 示例 2

 输入段：`[5, 2, 3, 4]`， 询问`(1,2)`| j | 一个[j] | 比较| 行动|
 | ---| ---| ---| ---|
 | 1 | 2 | 2！= 5 | 输出1 2，停止|

 不同的元素紧邻第一个元素，产生`(1,2)`。 

这些痕迹确认算法始终找到第一个有效对或正确报告没有有效对。

 ## 边缘情况

 在长度为 2 的段中，两个元素相同，算法正确输出`-1 -1`因为扫描将第二个元素与第一个元素进行比较，没有发现任何差异。 在第一个和最后一个元素不同的段中，扫描到达最后一个元素并正确返回其索引。 该方法可以有效地处理最小段、最大段和全相等数组，而无需冗余操作。
