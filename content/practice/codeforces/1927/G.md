 ## 解决方案
 ## 问题理解

 我们得到一个一维的单元条带，其中每个单元都包含一个具有固定半径的“油漆电荷”。 激活位置 i 处的电荷不仅会影响该单元格，还会绘制一个向左延伸或向右延伸恰好 a[i] 个单元格（包括原点）的连续段。 每个费用最多可以使用一次，我们可以完全忽略它。 

目标是激活最少数量的电荷，以便条带中的每个单元至少被涂漆一次。 重叠是允许的并且并不重要，因此这纯粹是用尽可能少的有向间隔覆盖整个索引范围，其中每个间隔来自为所选索引选择一个方向。 

每个测试用例的约束都很小，n 最多为 100，测试中的总 n 最多为 1000。这立即排除了每个测试用例比 O(n³) 更糟糕的情况，但更重要的是，它允许在间隔或位置上进行动态编程，并尝试下一个操作的所有选择。 

一个天真的想法是将每个电荷视为产生两个候选间隔，然后尝试所有电荷子集。 但这会失败，因为每个选择都取决于方向以及与已覆盖区域的相互作用。 另一种常见的错误尝试是贪婪选择覆盖最左侧未覆盖单元格的最长间隔，但方向性破坏了贪婪最优性。 看起来局部最优的电荷可能会浪费其延伸方向并阻碍以后更好的覆盖。 

关键的困难在于每个索引贡献两个不对称区间，我们必须选择一个以最小基数覆盖整条线的子集。 

## 方法

 强力方法将尝试所有电荷子集，并为每个子集尝试所有左或右方向。 每个配置生成最多 n 个间隔，验证覆盖范围为 O(n)，给出大约 O(3ⁿ) 的行为。 即使 n = 100，这也是不可能的。 

一旦我们注意到重要的不是我们在全球范围内选择哪些费用，而是我们如何从左到右逐步覆盖该细分市场，该结构就变得易于管理。 一旦覆盖了某个前缀，下一个决定本质上是选择一种收费，从某个起点尽可能远地扩展覆盖范围，可能会跳过已经覆盖范围内的一些小区。 

这自然会导致位置上的 DP，其中我们将每个单元格视为潜在的“未覆盖区域的开始”，并计算到达或通过每个位置所需的最小间隔数。 从每个位置 i，我们可以考虑所有电荷 j ≥ i，并在覆盖 i 的方向上模拟使用 j，这会产生最远的可到达端点。 该转换成为索引上的最短路径。 

因为n很小，我们可以为每个i和每个j预先计算在适当的方向上使用j来覆盖i的效果，然后放松dp转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集 | O(3ⁿ) | O(n) | 太慢了 |
 | DP 位置 + 转换 | O(n3) | O(n²) | 已接受 |

 ## 算法演练

 我们将 dp[x] 定义为覆盖位置 x 之前的所有单元所需的最小电荷数，解释为 dp[0] = 0 且其他状态初始化为无穷大。

1. 我们将覆盖视为从左到右的单调过程。 任何有效的解决方案都可以被视为将当前覆盖范围扩展到正确边界的一系列段。 这是有效的，因为一旦前缀被完全覆盖，内部重叠对于正确性就不再重要。 
2. 对于每个起始位置 i，我们尝试选择一个电荷 j 作为下一个活跃区间贡献者。 电荷可用于向左或向右扩展覆盖范围，但只有实际覆盖 i 的选项才相关，因为 i 是 DP 状态中第一个未覆盖的点。 
3. 如果我们在右侧使用 j，它会覆盖 [j, j + a[j] - 1]，因此仅当 j ≤ i ≤ j + a[j] - 1 时才对状态 i 有用。如果我们在左侧使用 j，它会覆盖 [j - a[j] + 1, j]，因此在 j - a[j] + 1 ≤ i ≤ j 时才有用。 
4. 一旦选择了有效方向，我们就会计算从该操作可到达的最远右端点。 该端点成为 dp 中的下一个候选状态。 我们用 dp[i] + 1 更新该端点处的 dp。 
5. 我们以升序对所有 i 重复这种松弛，确保当我们处理 i 时，dp[i] 已经反映了达到它的最佳方式。 

该算法有效地在边代表使用电荷覆盖一段的位置上构建有向图，并且我们计算从 1 到 n 的最短路径。 

### 为什么它有效

 任何有效的解决方案都对应于一系列已使用的费用，其中每个费用都必须覆盖使用时第一个未覆盖的位置。 这通过增加覆盖范围产生了独特的间隔排序。 DP 通过始终从最左边的未覆盖位置扩展并考虑可以覆盖它的所有费用来准确执行此顺序。 由于每个有效的解决方案都可以分解为这样的序列，并且考虑每个转换，因此 DP 不会错过更好的构造。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**9

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        dp = [INF] * (n + 1)
        dp[0] = 0
        
        for i in range(1, n + 1):
            # compute best ways to reach i as a covered prefix end
            best = dp[i]
            for j in range(1, n + 1):
                if dp[j - 1] == INF:
                    continue

                # use j to cover a segment that reaches i or beyond
                # try left orientation
                l = j - a[j - 1] + 1
                r = j
                if l <= i <= r:
                    best = min(best, dp[l - 1] + 1)

                # try right orientation
                l = j
                r = j + a[j - 1] - 1
                if l <= i <= r:
                    best = min(best, dp[l - 1] + 1)

            dp[i] = min(dp[i], best)

        print(dp[n])

if __name__ == "__main__":
    solve()
```DP 数组按照我们从左侧覆盖的距离进行索引。 对于每个端点 i，我们尝试所有可能的费用作为帮助到达或通过 i 的最后一段。 转换显式地计算段贡献的起点，并将问题简化为先前解决的前缀。 

关键细节是我们仅从 dp[l - 1] 转换，而不是从 dp[i - 1] 转换，因为所选段可能早于 i 开始，但仍负责覆盖 i。

 ## 边缘情况

 所有 a[i] = 1 的完全均匀数组强制每个单元被独立覆盖。 该算法正确分配 dp[i] = i，因为没有任何分段可以超出一个小区，并且每次转换仅将 dp 提高一个覆盖单位。 

第一个位置具有非常大的 a[i] 的情况会立即使 DP 崩溃，因为从索引 1 开始的右向区间覆盖了整个前缀，设置 dp[n] = 1。DP 考虑到这一点，因为每个 i 都会检查 j = 1，确保不需要特殊的大小写。 

严格递增的数组确保后面的位置可以覆盖更大的后缀，但不能覆盖前面的后缀，从而迫使 DP 正确比较多个部分覆盖。 松弛步骤确保考虑所有有效的开始，因此局部最优的早期选择不会阻碍更好的全局分割。
