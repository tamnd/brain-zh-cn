 ## 解决方案
 ## 问题理解

 我们得到一个数组`a`描述了如何构建隐藏字符串。 

对于每个位置`i`，值`a[i]`告诉我们角色在该位置出现了多少次`i`已经出现在字符串的前面。 如果`a[i] = 0`，这个角色以前从未出现过。 如果`a[i] = 2`，同一个字符在该位置之前已经出现了两次`i`。 

我们的任务是重建其踪迹与给定数组匹配的任何小写字符串。 

关键的观察结果是跟踪并不关心使用哪个特定字母。 它只关心该字母在放置时已经出现过多少次。 

所有测试用例的总长度最多为`2 · 10^5`，因此解必须接近线性时间。 一个`O(n²)`方法将大致执行`4 · 10^10`最坏情况下的操作，远远超出了极限。 需要线性或近线性解。 

如果不仔细选择重建逻辑，有几种情况可能会导致错误。 

考虑：```
a = [0, 1, 2, 3]
```唯一有效的结构重复使用相同的字符：```
aaaa
```在位置 3，我们需要一个已经出现过 3 次的角色。 选择一个新字母将立即违反跟踪。 

另一个例子是：```
a = [0, 0, 0, 0]
```一个有效的答案是：```
abcd
```重复使用相同的字符会产生跟踪值`[0,1,2,3]`反而。 

一个更微妙的情况是：```
a = [0, 0, 1]
```第三个字符必须与第二个字符匹配，而不是第一个字符。 该跟踪恰好需要先前发生的一次。 如果我们选择第一个字符，它的出现次数已经是一个，但是在使用它之后，跟踪将对应于不同的构建历史。 我们必须仔细跟踪每个字母当前的频率。 

该声明保证至少存在一个有效答案，因此我们永远不需要检测不可能性。 

## 方法

 直接的暴力重建是很容易想象的。 

从左到右处理字符串。 对于职位`i`，尝试每一个字母`'a'`到`'z'`。 对于每个候选字母，计算它在部分构造的字符串中较早出现的次数。 如果该计数等于`a[i]`，放置该字母并继续。 

这是可行的，因为可以直接检查跟踪的定义。 问题是效率。 通过扫描已构建的前缀成本来计算以前的出现次数`O(n)`每封信。 每个位置最多测试 26 个字母，复杂性变为`O(26·n²)`，这对于`n = 2 · 10^5`。 

跟踪的结构提供了一个更简单的解决方案。 

假设我们知道每个字母的当前频率。 如果出现字母`k`到目前为止，那么现在放置它会产生跟踪值`k`，因为正是`k`以前的情况已经存在。 

这意味着位置`i`只需要一个当前频率等于的字母`a[i]`。 

由于只有26个小写字母，我们可以维护每个字母的出现频率，并搜索计数匹配的字母`a[i]`。 选择后，我们将该频率增加一。 

该声明保证存在有效的答案，因此这样的信件将始终可用。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳 | O(26·n) = O(n) | O(26·n) = O(n) | O(26) | 已接受 |

 ## 算法演练

 1. 创建数组`cnt`大小为 26，用零初始化。`cnt[j]`存储多少次字母`j`已经被使用了。 
2. 从左到右处理迹线。 
3. 对于当前值`a[i]`，找到当前频率等于的任何字母`a[i]`。 
4. 将该字母附加到答案字符串中。 
5. 将该字母的出现频率增加 1，因为它现在再次出现。 
6. 继续，直到处理完所有位置。 
7. 输出构造好的字符串。 

步骤 3 中的搜索最多检查 26 个字母，这实际上是常数时间。 

### 为什么它有效

 每时每刻，`cnt[c]`等于字符出现的次数`c`已经放在前缀中了。 

当我们放置一个当前频率为`k`， 确切地`k`该字符的副本存在于当前位置之前。 根据定义，该位置产生的跟踪值为`k`。 

该算法总是选择频率等于所需值的字符`a[i]`，因此在位置生成的迹线`i`是完全正确的。 

放置角色后，其频率增加一，为未来的位置保留不变性。 由于保证输入来自某个有效的字符串，因此始终存在合适的字符。 因此，每个位置都被正确构造，并且最终的字符串完全具有所需的轨迹。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        cnt = [0] * 26
        ans = []

        for x in a:
            for j in range(26):
                if cnt[j] == x:
                    ans.append(chr(ord('a') + j))
                    cnt[j] += 1
                    break

        print("".join(ans))

solve()
```数组`cnt`存储每个小写字母的当前出现次数。 对于每个跟踪值`x`，我们搜索一个频率恰好为的字母`x`。 

一旦找到这样的字母，我们就会将其附加到答案中并增加其频率。 不变量是在处理位置之前，`cnt[j]`等于字母出现的次数`j`已经存在于构造的前缀中。 

一个常见的错误是试图仅跟踪最后使用的字符或仅跟踪之前出现过的字符。 跟踪取决于确切的出现次数，因此必须保留所有 26 个频率。 

另一个微妙之处是操作顺序。 我们必须比较`cnt[j]`和`x`在增加它之前。 首先递增会将每个跟踪值移动一位并产生不正确的结果。

 ## 边缘情况

 考虑：```
n = 1
a = [0]
```最初每个字母的频率都是 0。算法选择`'a'`，将其计数增加到 1，并输出：```
a
```踪迹是`[0]`，这是正确的。 

现在考虑：```
n = 4
a = [0, 0, 0, 0]
```频率开始为：```
a:0 b:0 c:0 d:0 ...
```该算法重复选择第一个计数为0的字母。使用后`'a'`，其计数变为 1，因此下一个可用的 count-0 字母是`'b'`， 然后`'c'`， 然后`'d'`。 

结果是：```
abcd
```每个位置对应于第一次出现，与跟踪完全匹配。 

最后考虑：```
n = 3
a = [0, 0, 1]
```处理完前两个位置后：```
string = "ab"
counts = {a:1, b:1}
```现在所需的跟踪值为 1。频率为 1 的第一个字母是`'a'`，因此算法输出：```
aba
```轨迹变为：```
[0, 0, 1]
```与输入匹配。 该示例说明了为什么需要跟踪精确的频率。 该决定取决于当前出现的次数，而不是字母之前是否出现过。
