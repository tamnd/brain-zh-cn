 ## 解决方案
 ## 问题理解

 我们被要求为从 2 到 n 的每个整数分配一个标签。 这些标签是正整数，并且它们必须满足强交互规则：每当两个数字没有大于 1 的公约数时，这意味着它们是互质的，它们分配的标签必须不同。 

重新表述这一点的一个有用方法是将每个整数 i 视为图中的一个节点，如果它们的 gcd 为 1，我们就连接两个节点。任务变成为节点分配颜色，以便该“互质图”中的相邻节点始终具有不同的颜色，同时使用尽可能少的颜色。 

输出只是 2 到 n 的分配颜色列表，并且在所有有效着色中，我们希望最小化所使用的最大颜色值。 

约束 n ≤ 100000 意味着任何比较所有数字对的方法都是不可能的。 所有对的二次甚至接近二次构造将大大超出时间限制。 我们需要一些更接近线性或线性算数行为的东西，最好使用数论结构而不是成对检查。 

这里常见的失败模式是尝试贪婪分配：根据先前分配的互质数为每个数字提供尽可能小的未使用颜色。 这种情况会失败，因为根据所有先前的数字确定互质性太慢，而且即使优化的簿记也往往会错过全局结构。 另一个错误是尝试通过奇偶校验或简单的模块化模式（例如 i mod k）来着色； 这些失败是因为互质性与算术残差类不一致。 

隐藏的结构是互质性受素数因子控制。 如果两个数字共享一个质因数，则它们不需要不同； 如果它们不共享任何素因数，那么它们必定不同。 这表明按最小质因数或可整除结构对数字进行分组。 

## 方法

 一种蛮力的想法是一次分配一个数字的颜色。 对于每个 i，我们扫描所有先前分配的数字 j 并检查 gcd(i, j)。 如果 gcd 为 1，我们确保 i 和 j 不共享颜色。 这可以通过重复检查整除性或计算 gcd 来实现。 

这种方法是正确的，因为它直接强制执行约束，但速度太慢。 对于每个 i，我们可以与所有先前的值进行比较，在最坏的情况下导致大约 O(n^2) gcd 计算。 当 n = 10^5 时，这远远超出了可行的限制。 

关键的观察是翻转视角。 我们不是直接防止互质数之间的冲突，而是构建永远不会发生冲突的群。 一个重要的事实是，共享相同素数因子的所有数字永远不会因仅与该素数有关的互质性而被迫不同。 这暗示底漆本身可以充当颜色代表。 

最佳构造出人意料地简单：为每个数字分配等于其最小质因数的颜色。 每个合数都继承其最小素因数的颜色，并且素数的颜色等于它们自己。 

这是有效的，因为如果两个数字是互质的，则它们不能共享任何质因数，特别是它们不能共享相同的最小质因数。 因此它们必须有不同的颜色。 这自然也可以最大限度地减少使用的颜色数量，因为每个素数都会引入一种新颜色，而每个复合材料都会重复使用现有的颜色。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(1) 或 O(n) | 太慢了 |
 | 最优（最小素因子着色）| O(n log log n) | O(n log log n) | O(n) | 已接受 |

 ## 算法演练

1. 使用类似筛子的过程预先计算 2 到 n 之间每个整数的最小素因子 (SPF)。 这使我们能够快速确定每个数字的“颜色”。 SPF 有用的原因是它将每个数字的因子结构压缩为单个代表性素数。 
2. 初始化一个大小为n+1的数组spf，其中spf[i]最终将存储整除i的最小素数。 首先假设所有 i 都为 spf[i] = i，因为每个数字最初都被视为潜在素数。 
3. 从 2 迭代到 n。 当我们遇到仍然有 spf[i] = i 的数字 i 时，我们知道它是素数。 对于 i 的每个倍数 j，如果尚未设置 spf[j]，则指定 spf[j] = i。 这确保每个数字都有其最小的素因数。 
4. 筛选完成后，指定 color[i] = spf[i]。 这直接定义了颜色。 
5. 按顺序输出从 2 到 n 的所有 i 的颜色。 

### 为什么它有效

 不变的是 spf[i] 总是存储除 i 的最小素数。 这确保了共享最小素数因子的所有数字都被分组在相同的颜色下，并且当较小的素数除以它时，不会错误地为数字分配更大的素数。 

如果两个数 i 和 j 互质，则它们根本不共享质因数。 因此 spf[i] 和 spf[j] 必须不同，因为相等意味着共享素数因子。 因此，始终满足着色约束。 同时，每个素数恰好引入一种新颜色，因此不会发生不必要的分裂。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    spf = list(range(n + 1))

    for i in range(2, n + 1):
        if spf[i] == i:  # i is prime
            for j in range(i, n + 1, i):
                if spf[j] == j:
                    spf[j] = i

    res = []
    for i in range(2, n + 1):
        res.append(str(spf[i]))
    print(" ".join(res))

if __name__ == "__main__":
    solve()
```筛部分构建最小素因子数组。 关键细节是条件`if spf[j] == j`，这确保我们只分配到达每个数字的第一个（最小）素数。 如果没有这个保护，后面的素数将覆盖正确的值并破坏正确性。 

输出循环直接打印 SPF 作为颜色，避免任何额外的映射或压缩。

 ## 边缘情况

 对于 n = 2，筛子指定 spf[2] = 2 并立即输出单个值。 该算法永远不会进入超过 i = 2 的内部标记循环，并且由于没有要检查的对，因此正确性微不足道。 

当 n = 3 时，素数 2 和 3 呈现不同的颜色。 由于 2 和 3 是互质的，因此它们一定不同，并且算法准确地产生了不同的结果。 

对于 n = 4，值 4 不是质数，并且从 2 获取其 SPF。这会创建 2 和 4 之间的重复颜色模式，这是安全的，因为 gcd(2,4) ≠ 1。该算法自然会避免为 4 分配新颜色，从而确认极小性。
