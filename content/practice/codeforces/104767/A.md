 ## 解决方案
 ## 问题理解

 输入描述了在编码为平衡括号序列的树状结构中的遍历。 每个左括号对应于进入一个新发现的房间或从遍历的较深处重新访问一个房间，而每个右括号对应于从一个房间返回到遍历历史中先前看到的祖先。 遍历始终从根开始和结束，因此括号形成有效的平衡序列。 

转换规则将这个遍历记录变成一个算术表达式。 最终表达式中每对相邻的符号都取决于序列中两个连续的括号。 关键思想是字符串中的每个位置都不是独立的，其贡献取决于相邻括号的局部关系。 任务是在应用这些本地替换规则后评估结果表达式。 

由于序列的长度最多为 100，因此任何二次解或稍差的解都已经足够了。 这消除了对渐近优化的担忧，并将焦点完全转移到正确地将括号序列中的结构关系转换为算术贡献。 

当出现多个相同的连续括号时，会出现微妙的失败情况。 例如，在像“)))”这样的前缀中，规则在每对连续的右括号之间引入了特殊的“+1”贡献。 仅考虑匹配对或堆栈匹配而不处理相邻关系的简单方法将完全错过这些贡献。 类似地，像“(()())”这样的序列混合了嵌套结构和邻接效应，因此将其仅视为平衡括号评估将产生不正确的结果。 

## 方法

 对问题的直接解释是模拟表达式是如何构造的。 人们可以首先通过扫描相邻对并根据规则插入符号来显式构建表达式，然后使用基于堆栈的解析器或递归下降来评估生成的算术表达式。 这是正确的，因为转换规则纯粹是局部的，并且最终表达式是整数和乘法的有效算术表达式。 

然而，构建完整的表达式是不必要的。 规则的结构允许我们在括号字符串的单次扫描期间直接计算贡献。 根据对类型，每个相邻对恰好贡献三个可能值之一。 这将问题转化为评估局部贡献的总和，而不是构建完整的表达式树。 

如果扩展到大尺寸或通过显式字符串扩展和解析实现，暴力方法只会在效率上失败，但更重要的是，它会引入不必要的复杂性和解析错误的空间。 优化的解释完全避免了表达式构建，直接累加相邻关系的数值结果。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 构建表达式 + 评估 | O(N²) | O(N²) | 已接受（矫枉过正）|
 | 直接邻接评估| O(N) | O(1) | O(1) | 已接受 |

 ## 算法演练

 核心思想是遍历括号序列并将每个相邻对解释为有助于最终总和的规则。

1. 从左到右扫描字符串，检查每对连续字符。 每对代表构造表达式中的一次插入，因此每对都必须精确计算一次。 
2. 如果该对是“()”，则这对应于贡献值1的匹配步骤。这是最简单的结构单元，表示在同一嵌套级别处向前移动，紧接着向后返回。 
3. 如果该对是“)(”，则这对应于在相反方向的两个单独的子结构之间移动，这有助于乘以1，因此它不会改变累加值。
 4. 如果该对是“))”，则表示遍历中连续返回，根据规则，它们之间贡献“+1”，所以我们将结果加1。 
5. 如果该对是“((”，则表示连续向前扩展为更深的结构，不直接贡献值，可以忽略。
 6. 将每对相邻对的所有贡献相加以获得最终答案。 

唯一重要的推理步骤是认识到每个局部模式独立地确定贡献并且不需要全局解析或匹配。 

### 为什么它有效

 遍历编码保证影响最终表达式的每个结构交互都被邻接捕获。 嵌套结构仅影响出现的对，而不影响它们的贡献方式。 由于每个规则仅依赖于两个连续的字符，因此表达式分解为独立的局部贡献。 这创建了一个不变量：处理前 i 对后，累积和等于由前 i 局部替换引起的部分构造表达式的值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    
    ans = 0
    
    for i in range(n - 1):
        a, b = s[i], s[i + 1]
        
        if a == '(' and b == ')':
            ans += 1
        elif a == ')' and b == ')':
            ans += 1
        elif a == ')' and b == '(':
            ans += 0
        else:
            pass
    
    print(ans)

if __name__ == "__main__":
    solve()
```该实现完全依赖于扫描相邻对一次。 关键细节是只有两种模式提供非零值：“()”和“))”。 另外两种模式要么对应于中性乘法，要么对应于不增加价值的结构转换。 这避免了对故事中描述的表达式进行堆栈处理或显式构造的需要。

 ## 边缘情况

 一种边缘情况是由连续的右括号（例如“）））））”主导的序列。 在这种情况下，每个相邻对贡献 1，因此该算法恰好累积了 N-1 个贡献。 扫描自然地处理这个问题，因为每个“))”都会触发增量，而不需要任何结构匹配。 

另一个边缘情况是完全嵌套的序列，如“(((())))”。 在这里，只有特定的转换起作用，并且算法仍然独立地处理每个相邻对。 结果仅来自更深层次嵌套和返回之间的边界，并且扫描可以正确捕获这些点，而无需显式跟踪深度。
