 ## 解决方案
 ## 问题理解

 我们得到一个代表一行单元格的一维二进制数组。 每个单元格要么处于非活动状态（显示为点），要么处于活动状态（显示为 X）。从这个初始配置开始，我们重复将行演化固定数量的步骤。 每个新行都是使用固定的本地规则从前一行同时计算的。 

该规则着眼于每个位置及其紧邻的左右邻居。 这三个单元形成了一个大小为 3 的窗口，并且在这样的窗口上有八种可能的 0 和 1 模式。 该规则被编码为 0 到 255 之间的数字，可以将其解释为一个查找表，告诉我们对于八个可能邻域中的每一个，中心单元的下一个状态应该是什么。 

输出需要在重复应用此规则后打印前 K 个生成的配置，每个配置在其自己的行上，使用相同的点和 X 编码。 

约束很小：宽度最多为 250，步数最多为 200。这立即表明直接模拟就足够了，因为每次生成都在宽度上花费线性时间，并且每个规则应用程序的总工作最多约为 50,000 个单元格更新。 即使每步都进行完全重新计算，操作总数仍然很小。 

一个微妙的边界条件是该行在概念上被无限零包围。 这意味着当我们计算第一个和最后一个单元格的邻居时，缺失的邻居将被视为点。 忘记此扩展的幼稚实现将默默地移动或缩小边缘的模式。 

另一个常见错误是误解规则编码。 规则编号不会直接作为二进制字符串应用于朴素的从左到右映射中，除非我们仔细定义哪个邻域对应于哪个位。 正确的映射是固定的：邻域从 111 到 000 排序。 

## 方法

 暴力方法直接遵循定义。 对于每一代，我们通过迭代每个单元并检查其左、中、右邻居来计算一个新数组。 对于每个三元组，我们确定它与八个二进制模式中的哪一个匹配，然后索引到规则表中以确定下一个状态。 这是简单且正确的，但每代仍需要 O(n) 工作量，总体上为 O(nK)。 

当 n 达到 250，K 达到 200 时，这最多需要 50,000 次单元更新，这已经是微不足道的了。 除了干净的模拟之外，不需要进行优化。 唯一真正的困难是正确实施规则解码和处理边界。 

关键的观察是，这是一个纯粹的局部确定性自动机。 每个单元更新仅取决于固定半径邻域，因此没有全局结构或预计算可以提供进一步帮助。 最佳解决方案是简单地仔细模拟，并从规则整数中提取正确的位。

 ## 算法演练

1. 将输入字符串转换为二进制数组，其中 X 变为 1，dot 变为 0。这使得邻居计算直接并避免重复的字符比较。 
2. 将规则整数解码为 8 位列表。 最低有效位对应于模式 000，最高有效位对应于 111。此映射必须与邻域的解释方式一致。 可以使用位移位来提取规则。 
3. 对于 K 代中的每一代，创建一个相同长度的新数组。 
4. 对于当前数组中的每个位置 i，通过读取左、当前和右单元格来计算邻域值。 如果 i 位于边界，则将超出范围的邻居视为 0。这确保了无限零假设得到尊重，而无需特殊的外壳单独逻辑。 
5. 使用位打包将三元组（左、中、右）转换为 0 到 7 之间的索引，然后使用该索引查询规则表并分配新值。 
6. 填充新数组后，将其转换回输出格式并打印。 然后用新数组替换当前数组并重复。 

### 为什么它有效

 每个单元更新仅依赖于固定半径1，因此下一代完全由前一代决定，没有任何隐藏的依赖关系。 规则表是从邻域状态到下一个状态的完整函数，因此每个配置都确定性地演化。 由于边界单元总是在数组外部看到零，因此模拟与问题中描述的无限扩展完全匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    R, K = map(int, input().split())
    s = input().strip()

    n = len(s)
    cur = [1 if c == 'X' else 0 for c in s]

    rule = [(R >> i) & 1 for i in range(8)]

    for _ in range(K):
        nxt = [0] * n

        for i in range(n):
            left = cur[i - 1] if i - 1 >= 0 else 0
            mid = cur[i]
            right = cur[i + 1] if i + 1 < n else 0

            idx = (left << 2) | (mid << 1) | right
            nxt[i] = rule[idx]

        print("".join('X' if x else '.' for x in nxt))
        cur = nxt

if __name__ == "__main__":
    solve()
```该解决方案首先将字符串转换为整数，以便按位运算变得自然。 规则解码步骤构建由邻域模式索引的直接查找表。 

关键的实现细节是索引公式`(left << 2) | (mid << 1) | right`，它将三位模式编码为 0 到 7 之间的数字。这必须与规则整数的解包方式相匹配。 

边界处理直接嵌入到邻居提取中，其中缺失的索引贡献为零。 这避免了核心循环内的边缘条件分支。

 ## 边缘情况

 一个关键的边缘情况是单单元格输入。 例如：```
128 2
X
```在第一次更新时，两个邻居都被视为零，因此唯一的邻居是 000，它映射到特定的规则位。 解码规则 128 后，只有 111 产生 1，因此该单元立即变为点并保持点状态。 该算法自然地处理这个问题，因为两个邻居都默认为零。 

另一个边缘情况是完全空的行：```
30 3
........
```每个邻域在第一步都是 000，所以整个下一代仅依赖于rule[0]。 该算法在各处正确地应用相同的索引计算，因此不需要特殊的套管。 

最后的边缘情况是最大宽度。 Even with 250 cells, the algorithm still recomputes each row independently, and the fixed-size arrays ensure no dynamic overhead beyond simple indexing, so performance remains stable.
