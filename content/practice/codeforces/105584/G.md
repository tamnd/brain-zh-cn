 ## 问题理解

 我们得到了几个独立的数据集。 每个数据集描述了具有多个参与者的游戏设置，每个参与者报告一个整数，该整数是两个隐藏值的总和。 

在幕后，有两副牌，红色和蓝色，每副牌恰好包含每个参与者一个整数。 两副牌都包含相同的整数多重集，但红牌和蓝牌之间的配对未知。 每个参与者都会收到一张红卡和一张蓝卡，并报告他们收到的两张值的总和。 

任务是确定是否存在对红卡和蓝卡的任何整数分配，以便所有报告的总和与两个相同多重集的某些配对一致。 如果可能的话，我们必须构造一个这样的配对分配。 否则，我们报告不可能。 

关键的隐藏结构是，我们将多重集分成两个相同的副本，然后在排列后按位置对元素进行配对，并且只观察到成对的和。 

每个数据集的约束很小，最多有 70 名左右的参与者。 这立即排除了对所有赋值排列的指数枚举，因为这将是 70 个阶乘可能性的量级，远远超出任何可行的计算。 如果在多个数据集上重复，即使是 O(n^4) 配对的强力构造也已经太大了。 

主要的微妙之处在于我们不能自由地独立分配任意对匹配总和。 相同的值必须在整体上恰好出现两次，每副牌中一次，这将全局范围内的所有选择结合起来。 

朴素贪婪配对的常见失败情况是局部和匹配有效但全局多重集一致性失败。 

例如，假设我们贪婪地为第一个参与者选择一个值，并尝试独立地在第二副牌中强制其补充。 我们稍后可能会发现我们用完了所需值的副本。 这种情况发生在以下情况：

 输入：

 n = 3

 s = [0, 0, 0]

 一种简单的方法可能会将 (0,0) 分配给每个参与者，但这假设我们可以自由地重用相同的多重集，而无需跟踪全局一致性。 这恰好适用于这里，但在更结构化的情况下，例如：

 输入：

 n = 3

 s = [1, 1, 2]

 贪婪的尝试可能会分配 (0,1), (0,1), (1,1) ，这会破坏多重集相等性。 

因此核心困难是配对约束下两个相同多重集的全局一致性。 

## 方法

 蛮力的想法是显式地为两个牌组分配值。 由于每个参与者贡献一对 (a[i], b[i]) 并且两个多重集必须匹配，因此我们可以尝试生成大小为 n 的所有可能的多重集，然后检查是否存在产生给定总和的配对。 这将涉及选择 n 个整数，复制它们，然后将它们成对匹配并与总和一致。
