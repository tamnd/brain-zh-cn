 ## 解决方案
 ## 问题理解

 我们正在模拟一个非常小的“播放列表系统”，它通过一系列操作而演变。 任何时候都有一队歌曲等待表演。 两种操作按顺序发生。 

一个操作会从队列前面删除并执行一首歌曲（如果存在）。 另一个操作将新歌曲添加到队列末尾。 关键的变化是添加的批次越来越多：第一次添加歌曲时，我们只添加一首； 第二次添加歌曲时，我们正好添加两首； 第三次三，依此类推。 

执行完所有操作后，队列中仍有一些歌曲未执行。 我们被告知总共执行了多少次操作以及最后还剩下多少首歌曲。 任务是确定整个过程中实际演奏了多少首歌曲。 

输入大小非常小，操作数量最多为 10 个量级，因此任何指数推理或直接枚举所有有效操作模式的方法在概念上都是可以的。 然而，该结构仍然很重要，因为“增加批量大小”在添加多少歌曲和删除多少歌曲之间创建了隐藏的算术关系。 

一个微妙的点是，添加可以连续发生，这意味着可能会发生多个“添加批次”，而中间不会执行任何歌曲。 这使得不可能假设交替模式。 

一个天真的错误是假设每个操作都是独立的，并尝试在不跟踪不断增长的添加大小序列的情况下进行模拟。 另一个常见的错误是将添加的歌曲数量简单地视为“添加操作”的数量，从而忽略了三角形增长模式。 

例如，如果操作被安排为有两个添加操作和一个删除操作，则添加操作总共贡献 1 + 2 = 3 首歌曲。 如果一首歌曲被执行并剩下两首，则匹配一致的状态。 任何假设每次添加贡献恒定量的推理在此类输入上都将失败。 

核心困难是重建每种操作类型发生的次数，并将其与添加歌曲的三角和相结合。 

## 方法

 暴力破解的想法是尝试重建操作序列。 由于每个操作要么是“添加 k 首歌曲”（其中 k 取决于已经发生的添加次数），要么是“如果可能的话删除一首歌曲”，因此我们可以模拟与最终状态一致的所有有效序列。 对于每个候选序列，我们将跟踪一个队列，应用操作，并检查它是否以剩余的 m 首歌曲结束。 这是正确的，因为它直接反映了流程定义。 

然而，分支来自于决定n个操作中哪些是“添加”操作，哪些是“删除”操作。 在最坏的情况下，这意味着探索操作的所有子集，即 O(2^n)，即使 n 约为 10，这也是边界，但鉴于存在更简单的结构，这是不必要的。 

关键的观察结果是系统完全由两个数字决定：添加操作的数量和删除操作的数量。 如果我们让 a 为添加操作的数量，b 为删除操作的数量，则 a + b = n。 添加的歌曲总数与 a 不是线性关系，而是等于 1 + 2 + … + a = a(a+1)/2。 删除的歌曲总数为 b，但前提是队列永远不会变为负数，这由存在有效解决方案的问题陈述保证。 

所以最后剩下的歌曲满足：

 初始 + 添加 − 删除 = m

 假设初始值为零（该模型的典型值），我们得到：

 a(a+1)/2 − b = m

 由于 b = n − a，我们将所有内容简化为单个变量：

 a(a+1)/2 − (n − a) = m

这变成了a中的一个简单的二次方程。 由于 n 很小，我们可以尝试从 0 到 n 的所有 a 并检查哪一个满足方程。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力序列模拟 | O(2^n·n) | O(2^n·n) | O(n) | 太慢/不必要|
 | 尝试所有添加计数 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将这个过程解释为选择n个操作中有多少个是“加操作”，称这个值为a。 剩余的 n − a 操作是“删除操作”。 
2. 对于固定的a，计算通过添加引入了多少首歌曲。 由于每次添加都会增加 1，因此添加的歌曲总数形成一个三角形数 a(a+1)/2。 这准确地捕获了递增批处理规则。 
3. 计算删除了多少首歌曲，这只是 n − a，因为每个非添加操作都删除了一首歌曲。 
4. 计算添加的剩余歌曲数减去删除的歌曲数。 
5. 检查是否等于m。 如果确实如此，我们就发现了操作的一致分解，因此执行的歌曲数量恰好是 n − a。 
6. 由于约束很小，因此迭代从 0 到 n 的所有可能的 a 并返回唯一的有效结果。 

### 为什么它有效

 除了我们执行每种操作类型的次数之外，该进程没有隐藏状态。 递增添加规则仅取决于先前添加的计数，而不取决于它们在删除中的位置。 因此，任何具有添加的有效计划都会产生相同的总添加和，与顺序无关。 这将整个序列问题分解为单个参数 a。 最终队列大小仅取决于总添加量和总移除量，因此匹配 m 唯一地确定正确的分割。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    for a in range(n + 1):
        added = a * (a + 1) // 2
        removed = n - a
        remaining = added - removed
        if remaining == m:
            print(removed)
            return

if __name__ == "__main__":
    solve()
```该实现直接将归约编码为单个变量。 a 上的循环是安全的，因为 n 最多为 10，因此我们有效地枚举了所有可能的操作类型分割。 

三角计算`a * (a + 1) // 2`即使 Python 自然地处理大整数，也必须小心地使用整数运算来避免浮动问题。 

我们打印`removed`因为执行的歌曲数量恰好对应于发生的删除操作数量。

 ## 边缘情况

 最小的非平凡边是当 n = 0 时。在这种情况下，没有任何操作，因此无法执行任何歌曲，也不会添加任何歌曲。 唯一一致的状态是 m = 0，并且算法正确评估 a = 0、added = 0、removed = 0。 

另一种微妙的情况是所有操作都是一种类型。 如果全部相加，a = n，最终状态是纯三角形。 如果全部删除，则代数模型中 a = 0 并且最终状态为负，这在有效输入中不会发生，因此这种情况自然被“保证解”条件排除。 

最后，像交替添加和删除这样的混合情况仍然可以正确折叠，因为三角和仅取决于我们增加添加计数器的次数，而不取决于删除发生的位置。 对 a 的枚举隐式地涵盖了所有此类交错，而无需显式地模拟它们。
