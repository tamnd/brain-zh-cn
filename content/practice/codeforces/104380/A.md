 ## 解决方案
 ## 问题理解

 我们得到一个仅由字符组成的二进制字符串`0`和`1`。 我们可以重复找到任何相邻的模式`"01"`并将其从字符串中完全删除，从而关闭删除留下的间隙。 我们继续这样做，直到没有`"01"`子字符串存在于字符串中的任何位置。 任务是输出最终的稳定字符串及其长度。 

关于该过程的关键观察结果是，删除是局部的，但影响是全局的。 删除一个`"01"`可以创造新的`"01"`配对跨越了剩余内容的边界，因此删除的顺序在实现中很重要，但在最终结果中并不重要。 

输入大小可达`10^5`，这排除了任何重复扫描字符串并以幼稚的方式删除中间子字符串的方法。 单个删除可能会花费 O(n) 成本，在最坏的情况下，我们可以执行 O(n) 次删除，从而导致 O(n^2) 行为，这在约束下太慢了。 这立即表明我们需要线性或近线性模拟。 

当零和一以发生级联删除的方式交错时，就会出现微妙的边缘情况。 例如，在`"0101"`，删除第一个`"01"`树叶`"01"`再次，并且可以再次删除。 不重新考虑新形成的边界的幼稚的从左到右的单次传递将在这里失败。 

另一个重要的观察结果是该操作仅删除`"01"`， 绝不`"10"`。 这种不对称性决定了最终弦的结构。 

## 方法

 直接模拟方法维护字符串并重复扫描它`"01"`，删除出现的情况，直到没有出现的情况为止。 这是正确的，因为它准确地反映了允许的操作。 然而，每次扫描的时间复杂度为 O(n)，每次删除都会移动字符串，同样也是 O(n)。 在最坏的情况下，删除发生多次，例如交替模式，总运行时间变为二次。 

关键的见解是避免显式删除，而是使用类似堆栈的过程来模拟取消。 当从左到右扫描时，每当我们看到`1`，它可能会取消先前不匹配的`0`如果那样`0`在堆栈中立即可用。 每个`"01"`删除对应于配对a`0`出现较早且出现较晚的`1`。 这表明我们只需要跟踪有多少个不匹配的零仍然可用，并决定是否`1`取消其中之一或继续存在。 

这减少了维护单个计数器或零堆栈的问题。 每个`0`被推为未来取消的候选者，并且每个`1`删除一个这样的候选者（如果存在）。 剩下的是不匹配的零，后面跟着无法取消左侧任何内容的不匹配的零。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力重复删除 | O(n²) | O(n) | 太慢了 |
 | 堆栈/计数器模拟| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 从左到右扫描字符串，同时维护一个存储尚未删除的不匹配字符的堆栈。 

堆栈表示已处理前缀的当前简化形式。 
2. 对于每个角色，决定它是否构成可移动的`"01"`与堆栈顶部的模式。 

我们只删除`"01"`，所以唯一有用的取消是当我们看到`1`堆栈顶部是`0`。 
3. 如果当前字符是`0`，将其压入堆栈，因为它可能会被未来删除`1`。 
4. 如果当前字符是`1`，检查栈是否非空，栈顶是否为`0`。 如果是这样，弹出`0`，代表删除`"01"`一对。 否则推`1`到堆栈上。 
5. 处理完整个字符串后，堆栈包含最终的不可约字符串。 输出它的长度和内容。 

为什么它起作用：在扫描中的任何一点，堆栈都维护前缀的简化形式，没有内部`"01"`剩余对。 任何未来`1`只能与较早的互动`0`s，并且堆栈确保我们始终将 a 配对`1`与最新可用的`0`，这正是唯一的情况`"01"`可能会发生删除。 由于每个有效删除都被模拟一次并且没有引入无效配对，因此最终堆栈是唯一的固定点，其中没有`"01"`遗迹。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    stack = []

    for ch in s:
        if ch == '0':
            stack.append('0')
        else:
            if stack and stack[-1] == '0':
                stack.pop()
            else:
                stack.append('1')

    print(len(stack))
    print(''.join(stack))

if __name__ == "__main__":
    solve()
```该解决方案读取字符串一次并按顺序处理每个字符。 堆栈纯粹用作不匹配符号的模拟工具。 唯一重要的决定是在处理一个`1`：我们检查它是否可以取消前面的`0`。 这是唯一有效的删除模式，因此不需要其他情况。 

最终输出直接从堆栈构建，无需任何后处理。

 ## 边缘情况

 一个关键的边缘情况是当删除级联跨越先前分离的区域时。 考虑`0101`。 第一个`"01"`去除叶子`"01"`，这再次形成可移动的对。 堆栈自动处理此问题：处理后`0`，堆栈是`[0]`， 然后`1`弹出它，离开`[]`，然后下一步`0`推动，然后最后`1`再次弹出，导致堆栈空。 输出正确，无需重复扫描。 

另一种边缘情况是一个以许多 1 后跟零开头的字符串，例如`111000`。 既然没有`"01"`一旦出现，堆栈只会增长，并且算法会保留整个字符串。 这证实了该方法不会过度激进地删除`"10"`模式，这是不允许的操作。 

最后一种边缘情况是字符串变空。 任何序列如`000111`完全减少，因为每个零最终都会在其右侧找到匹配的一。 栈自然变空，算法正确输出长度`0`和一个空字符串。
