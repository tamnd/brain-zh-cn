 ## 解决方案
 ## 问题理解

 我们得到一个矩形网格，其中每个单元格都包含一个数字，描述该单元格周围特定邻域中存在多少个地雷。 邻域不仅是单元格本身，还包括通过角或边缘接触它的所有单元格，形成以该单元格为中心的 3 x 3 块。 因此，每个值实际上是其周围 8 个单元格中的地雷数量加上其本身。 

还有一个额外的结构限制：网格外边界不存在地雷。 这很重要，因为它保证每个有效地雷在网格内都有一个完全定义的 3 x 3 邻域，因此每个地雷以一致的模式贡献恰好 9 个单元格的计数。 

任务是重建所有地雷的精确坐标，并按行、然后按列排序输出它们。 

约束允许最多一千行和一千列，因此最多一百万个单元格。 任何试图测试所有可能的矿井配置的解决方案都是立即不可能的，因为状态空间的单元数量呈指数增长。 即使是每单元二次方法也有速度太慢的风险，因此我们正在寻找线性或近线性重建策略。 

一个微妙的点来自于将数字解释为二进制地雷网格上具有固定 3 x 3 核的局部卷积。 这意味着每个地雷对 9 个单元贡献 +1，并且重叠贡献总和。 

如果假设单元格的值直接对应于它是否是地雷，就会出现天真的陷阱。 例如，标记为 4 的单元格并不意味着它是或不是地雷，它仅反映周围的地雷。 另一种失败模式是尝试贪心演绎而不强制重叠邻域之间的一致性，这会导致矛盾。 

一个小的说明性混淆案例是 (2,2) 处的单个地雷。 其 3 x 3 邻域中的每个单元格都变为 1。如果我们独立地猜测每个单元格中的地雷，我们就会错误地将所有这 9 个单元格标记为地雷，严重地多算了。 

## 方法

 一个蛮力的想法是独立处理每个单元，并尝试通过检查涉及它的所有约束来推断它是否是一个地雷。 人们可以尝试假设一个单元是一个地雷，并从它接触的所有 3 x 3 邻域中减去它的影响，递归地继续，直到满足所有数字。 这很快就会变成回溯或约束满足问题。 在最坏的情况下，大约 100 万个单元格中的每一个都可能是地雷，也可能不是，从而导致 2^(mn) 种状态。 即使进行了修剪，重叠的约束也不足以减少分支因子以使其可行。 

关键的观察结果是该问题在结构上是线性的。 每个地雷恰好影响九个单元格，每个单元格的值是附近地雷贡献的总和。 这是一个网格上的固定线性系统，但更重要的是，它可以在确定性的从左到右、从上到下的扫描中局部求解。 

关键的想法是按照一定的顺序处理网格，在决定某个位置是否存在地雷时，对已处理单元的所有未来贡献都已经确定。 如果我们逐行遍历，我们可以根据 (i, j) 处当前剩余的所需贡献来“固定” (i, j) 处的决策，因为任何可能影响 (i, j) 的未来地雷必须位于其 3 x 3 邻域内，并且由于无边界地雷约束和处理顺序，这些未来位置以一致的方式控制。

我们维护一个工作网格，表示每个单元仍需要满足多少贡献。 当我们决定在 (i, j) 处放置地雷时，我们从其 3 x 3 邻域中的所有单元中减去 1。 如果我们不埋设地雷，我们就什么也不做。 正确性来自于这样的事实：在我们到达 (i, j) 的那一刻，所有上方或左侧仍然可能受到影响的单元格都已被最终确定。 

这将问题简化为带有局部校正的贪婪重建。

 ## 算法演练

 1. 读取网格并将其存储为表示剩余所需贡献的可变数组。 当我们放置地雷时，该网格将会更新，以便它始终反映未来决策仍需要解释的内容。 
2. 从上到下、从左到右遍历网格，跳过边界单元，因为它们保证不包含地雷。 这种排序确保了当我们决定选择一个单元格时，影响它的所有早期交互都已经得到解决。 
3. 在每个单元格 (i, j) 处，检查该单元格的当前剩余值是否大于零。 如果它为零，我们就不能证明在这里放置地雷是合理的，因为没有剩余的约束需要它，所以我们继续前进。 
4. 如果值为正，我们在 (i, j) 处放置一个地雷。 这是减少该位置剩余需求的唯一局部一致的方法，同时尊重每个地雷向该单元贡献一个单位。 
5. 放置地雷后，以 (i, j) 为中心的 3 x 3 邻域中的所有单元格减 1。 该模型模拟了地雷对所有受影响单元的影响，更新了它们剩余的所需贡献。 
6. 继续扫描，直到处理完所有有效的内部单元。 埋设地雷的位置就是最终的答案。 

关键的不变量是，在处理任何单元格 (i, j) 之前，已经应用了先前决定的地雷的所有修正，因此 (i, j) 处的值准确地表示仍然必须覆盖它的额外地雷数量。 贪心决策是安全的，因为任何可能影响 (i, j) 的未来矿井都必须位于稍后将被处理的区域，并且在做出自己的决策时，它们的贡献会被对称处理。 这可以防止过度使用：一旦单元格减少到零，它就永远不会再次错误地增加。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    m, n = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(m)]
    mines = []

    for i in range(1, m - 1):
        for j in range(1, n - 1):
            if grid[i][j] > 0:
                mines.append((i, j))
                for di in (-1, 0, 1):
                    for dj in (-1, 0, 1):
                        grid[i + di][j + dj] -= 1

    if not mines:
        print(0)
    else:
        mines.sort()
        for i, j in mines:
            print(i, j)

if __name__ == "__main__":
    solve()
```该解决方案维护网格的工作副本并直接模拟放置地雷的效果。 双循环确保我们按行主升序访问单元格。 条件`grid[i][j] > 0`决定那里是否必须存在地雷，因为此时任何积极的要求都必须立即由放置在当前单元格的地雷来满足。 

3 x 3 更新循环是核心转换，确保每个地雷都能正确贡献给所有受影响的单元。 最后的排序保证了所需的输出顺序，尽管遍历已经自然地产生了它。 

一个微妙的实现点是，我们永远不需要检查放置地雷是否会违反未来的约束，因为贪婪结构保证了按顺序处理时的一致性。 

## 工作示例

 我们使用提供的样本输入作为主要轨迹，因为它已经清楚地展示了重叠的邻域。 

让我们从概念上跟踪几个关键位置，而不是完全展开所有一百万个单元。 

一开始，每个单元都保留其初始所需的贡献。 

当我们到达单元格 (1,1) 时，它的值为正，因此我们在那里放置一个地雷，并从其周围的 3 x 3 块中减去 1。 这会立即降低附近单元格中的值，从而传播效果。 

当我们移动到 (1,3) 时，我们再次发现一个无法用早期放置来解释的正值，因此我们放置另一个地雷并应用相同的局部减量。 

当处理继续时，重叠的邻域会导致值自然地趋向于零，恰好在所有所需的地雷都已被考虑在内的情况下。 

小片段的简化跟踪：

 | 步骤| 职位| | 之前的网格[i][j] 行动| 效果|
 | ---| ---| ---| ---| ---|
 | 1 | (1,1) | >0 | 放置我的| 在 3x3 块中减 1 |
 | 2 | (1,3) | >0 | 放置我的| 在 3x3 块中减 1 |
 | 3 | (2,3) | >0 | 放置我的| 在 3x3 块中减 1 |

 这表明重叠的贡献是如何逐渐取消的。 

这里确认的关键行为是局部性：每个决策仅取决于单个单元的当前残差，并且更新一致地传播而无需回溯。

 ## 边缘情况

 一个关键的边缘条件是网格中根本不包含地雷。 在这种情况下，每个单元格从一开始就为零，因此扫描永远不会触发放置。 输出变为单个零，算法在遍历后显式处理该零。 

另一种情况是 3 x 3 网格中心的单个孤立地雷。 该算法访问中心单元格，看到一个正值，放置一个地雷，并立即从所有九个单元格中减去一。 更新后，每个单元格都变为零，并且不再放置更多地雷，这与预期的重建相匹配。 

一个更微妙的情况是多个重叠的地雷，其影响在不同地区之间抵消得不均匀。 因为每个放置都会立即将其影响传播到所有邻居，所以任何重叠都会自然地在残差网格中解决。 贪婪规则确保没有单元格留下正需求，除非相应的地雷已放置在仍然可以影响它的位置。
