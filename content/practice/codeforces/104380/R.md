 ## 解决方案
 ## 问题理解

 我们得到一个数字序列，然后通过按顺序处理它们来构建双端队列。 对于每个元素，我们独立决定是将其插入到前面还是后面。 每一个这样的选择序列都会产生一个最终的数组排序，并且所有$2^n$生成的双端队列在最终聚合中被同等考虑。 

对于每个可能的结果双端队列，我们​​计算位置值的总和$L$定位$R$，然后我们将这些值添加到所有可能的双端队列中。 任务是计算总贡献模数$10^9+7$。 

关键的困难在于每个元素的最终位置取决于其左侧或右侧放置了多少个较早和较晚的元素。 这就产生了一种全局依赖性：一个元素的贡献受到所有其他元素的影响。 

约束条件$n \le 5 \times 10^5$立即排除任何配置或排列的枚举。 甚至存储或迭代所有$2^n$结果是不可能的。 任何可行的解决方案都必须将问题简化为在线性或近线性时间内计算每个元素的贡献。 

当所有值都相等时，会出现微妙的边缘情况。 在这种情况下，不同的双端队列结构可能会产生相同的序列，但它们仍然被单独计数。 例如，如果所有$A_i = 1$,$n=3$, 每一个$2^3$建筑选择贡献相同的最终金额。 简单的排列重复数据删除方法会严重低估。 

另一个陷阱是假设最终排列是均匀随机排列。 它不是。 例如，与$A = [1,2,3]$，产生的排列是有偏差的，并且会出现重复，因为不同的决策序列可能导致相同的排序。 

## 方法

 蛮力方法模拟了所有$2^n$插入元素的方法。 对于每个配置，我们显式构建双端队列并计算间隔内的总和$[L, R]$。 这在概念上很简单：每个元素要么向左推，要么向右推，并且我们维护结果结构。 

问题在于配置的数量呈指数级增长。 甚至$n=25$已经产生了超过 3000 万个状态，而这里$n$高达500,000。 这使得暴力破解从根本上是不可行的。 

关键的观察是我们实际上不需要每个双端队列的完整结构。 我们只需要知道，对于每个元素，它在落在之间的位置时对最终答案有多少次贡献$L$和$R$。 我们不是跟踪完整的排列，而是计算所有构建序列中每个位置中出现的每个元素的概率加权计数。 

构建过程具有对称性：在步骤$i$, 元素$A_i$放置在左侧或右侧，但其与先前插入的元素的相对顺序仅取决于左侧或右侧放置的元素数量。 这导致了一种组合解释，其中每个元素的最终位置分布可以在不枚举所有序列的情况下进行表征。 

对于每个元素，我们计算剩余的有多少种方式$n-1$可以对元素进行排列，使其最终位于内部的有效位置$[L, R]$。 这减少了二项式系数的计算，即在较早的索引中将有多少元素放置在其左侧，在较晚的索引中将有多少元素放置在其左侧。 最终的解决方案成为贡献的线性组合，每个贡献均按 2 的幂和组合放置计数进行加权。

 ## 算法演练

 我们根据对位置的贡献而不是显式的双端队列构建来重新制定该过程。 

1.我们解释每个元素$A_i$作为对多个最终位置的贡献，具体取决于有多少剩余元素放置在其左侧或右侧。 我们不是跟踪完整的排列，而是计算将其放入给定排名的配置。 
2.对于固定元件$i$，假设它最终位于位置$k$。 这恰好发生在$k-1$其中的元素$n-1$在双端队列过程产生的最终排序中，元素被放置在它之前。 选择哪些元素落在左侧的方法数量贡献了二项式因子。 
3. 构造过程意味着分配“左插入”的每个元素子集确定一致的排序。 每个子集的贡献均等，权重为1，并且所有子集都是独立的选择。 这给出了所有的统一权重$2^n$施工顺序。 
4. 我们预先计算组合计数$C(n, k)$和 2 的幂，以便我们可以快速评估有多少个序列放置了元素$i$到里面的一个位置$[L, R]$。 
5. 对于每个元素$A_i$，我们计算它在区间内可以占据多少个有效的最终位置，乘以与该位置一致的构造序列的数量，并添加加权贡献$A_i$。 
6. 总结这些贡献$i$给出了最终答案。 

该实现简化为预先计算二项式系数的阶乘和逆阶乘，然后迭代所有元素以使用有效位置范围上的前缀和来累积它们的贡献。 

### 为什么它有效

 每个构造序列对应于每个元素的二元决策：左插入或右插入。 这些决策导致索引的独特排列，但多个决策序列可能会产生相同的排列。 然而，总贡献是在序列上定义的，而不是不同的排列，因此每个序列必须单独计算。 

关键的不变量是，元素的贡献仅取决于最终排序中在其之前放置的元素数量，而不取决于它们的身份。 因为“左选择”的每个子集在$2^n$序列，将元素放置在给定等级的序列数量仅取决于在其之前结束的其他元素的组合选择。 这将问题简化为计算大小子集$k$，它是由二项式系数精确捕获的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, L, R = map(int, input().split())
    A = list(map(int, input().split()))

    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)

    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(n, k):
        if k < 0 or k > n:
            return 0
        return fact[n] * invfact[k] % MOD * invfact[n - k] % MOD

    pow2 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow2[i] = pow2[i - 1] * 2 % MOD

    ans = 0

    for i in range(n):
        ways_total = pow2[n - 1]
        total = 0

        for pos in range(L, R + 1):
            if 1 <= pos <= n:
                total += C(n - 1, pos - 1)

        total %= MOD
        ans += A[i] * total % MOD * pow2[n - 1] % MOD
        ans %= MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```该代码预先计算阶乘和逆阶乘以支持快速二项式系数。 两个数组的幂表示固定一个元素的贡献时，剩余元素的决策序列总数。 

位置上的内循环是对最终排名的总和的直接转换$[L, R]$一个元素可以占据。 最终乘以$2^{n-1}$反映了一旦固定元素的相对排名确定，其余元素的所有左/右选择都保持自由。 

这里的一个常见的实现陷阱是忘记贡献计算的是决策序列而不是不同的排列。 这就是为什么每个有效的展示位置都会乘以$2^{n-1}$，未标准化。

 ## 边缘情况

 当$n = 1$，只有一个构造序列，并且双端队列包含单个元素。 该算法简化为返回$A_1$如果$L=1$。 任何组合逻辑都不得尝试无效的二项式范围。 

为了$n = 2$，每个元素都可能有两种插入顺序。 该算法必须确保两个序列单独计数，即使它们产生相同的最终排列。 这是重复计算的最小情况。 

什么时候$L = R$，只有一个位置有贡献。 实现必须正确隔离该排名； 在不仔细处理边界的情况下对范围求和会导致包含相邻位置和过度计数。 

当所有$A_i$相等，每个序列产生相同的和，但仍必须计数$2^n$次。 任何折叠相同排列的优化都会低估每个排列插入序列的数量。
