 ## 解决方案
 ## 问题理解

 我们得到一个从 0 到 n 的连续整数列表。 在每对相邻数字之间，我们可以插入一个加号或一个减号，从而有效地决定每个数字对运行总和的贡献是正还是负。 任务是确定是否存在符号选择，以便结果表达式的计算结果精确为 x，如果存在，则构造任何有效的表达式。 

表达式的结构是固定的，只是符号不同。 每个数字 i 贡献 +i 或 -i，因此问题简化为选择总有符号和与目标匹配的数字子集。 

约束很小，n 最多为 100。这立即排除了对高级优化技术或启发式修剪大量搜索的任何需要。 在多项式时间内运行的解决方案，即使是 O(n^2) 或 O(n^3)，也很容易足够快。 

一个关键的观察结果是，从 0 到 n 的所有数字的总和为 n(n+1)/2。 任何带符号的表达式都可以看作是从这个总和开始，然后翻转某些元素的符号，这实际上减去了所选元素总和的两倍。 这种对称性定义了从 -S 到 S 的可达范围，其中 S 是总和。 

当 x 超出此范围时，就会出现边缘情况。 例如，如果 n = 4，则 S = 10，因此 x = 15 是不可能的。 尝试在不检查可行性的情况下贪婪地分配符号的幼稚实现仍然可以生成表达式，但它不会与目标匹配。 

当存在多个结构时，会出现另一种微妙的情况。 该问题只需要任何有效的表达式，而不是字典顺序最小或任何最佳结构。 这允许从较大的数字向下进行贪婪的构造。 

## 方法

 暴力方法会尝试所有 2^n 符号分配。 每个分配对应于选择要求反的数字子集。 对于每个配置，我们计算结果总和。 这是正确的，因为它枚举了所有可能的表达式，但可能性的数量呈指数增长。 当 n = 100 时，这将变得非常大且无法使用。 

我们可以以更结构化的方式重新表述问题。 从总和 S = 0 + 1 + ... + n 开始。 如果我们决定给数字 i 分配一个负号，它的贡献就会从 +i 变为 -i，从而使总数减少 2i。 因此，选择一组数字进行求反相当于找到一个总和等于 (S - x) / 2 的子集。 

这将问题转化为一个具有较小 n 和较小总和 S ≤ 5050 的子集和。对可能的和进行动态规划方法是可行的，但我们甚至不需要完整的 DP，因为我们只需要一个构造，而不是计数或优化。 

贪婪构造之所以有效，是因为较大的数字提供了较大的调整能力。 我们处理从 n 到 1 的数字，决定翻转每个数字是否能让我们更接近剩余的所需调整。 这就像有界范围内的确定性子集和重建。

 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|

 ## 算法演练

 我们根据与完全正和的偏差重写目标方程。

1. 计算 S = n(n+1)/2。 这是所有符号均为正时的值。 
2. 如果 x 超出 [-S, S]，则立即返回 IMPOSSIBLE，因为符号翻转的组合不能超出这些界限。 
3. 定义所需的调整 D = S - x。 这是我们需要通过翻转符号减去的总金额。 
4. 如果 D 为奇数，则返回 IMPOSSIBLE。 每次翻转都会使总和改变 2i，因此所有调整都是均匀的。 
5. 现在我们需要选择总和等于 D/2 的数字。 
6. 初始化剩余=D/2。 
7. 将 i 从 n 迭代到 1。对于每个 i，如果 i ≤ 剩余，则选择对 i 取反并从剩余中减去它。 否则保持积极的态度。 
8. 始终将 0 保留为 +0，因为它不影响总和。 

构建符号分配后，我们输出表达式。 

它起作用的原因来自于在每一步中的不变量，剩余代表尚未处理的数字的有效子集和余数。 由于我们从大到小进行处理，因此在可能的情况下选择 i 不会妨碍未来的可行性：已经考虑了任何较大的数字，较小的数字足以完成剩余余数，因为剩余数字的总和始终主导任何可表示的剩余间隙。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    
    S = n * (n + 1) // 2
    
    if x < -S or x > S:
        print("IMPOSSIBLE")
        return
    
    D = S - x
    
    if D % 2 != 0:
        print("IMPOSSIBLE")
        return
    
    target = D // 2
    sign = ['+'] * (n + 1)
    
    for i in range(n, 0, -1):
        if i <= target:
            sign[i] = '-'
            target -= i
    
    expr = []
    for i in range(n + 1):
        expr.append(f"{sign[i]}{i}")
    
    print("".join(expr))

if __name__ == "__main__":
    solve()
```该实现直接遵循从符号分配到子集和的减少。 数组`sign`存储每个数字是正贡献还是负贡献。 我们将所有内容初始化为正值，然后在大数字适合剩余的所需调整时贪婪地翻转它们。 然后按从 0 到 n 的顺序打印表达式。 

一个微妙的点是所有符号都初始化为“+”。 这很重要，因为必须始终包含 0 并且不应该影响正确性。 另一个是从 n 向下迭代，确保首先决定较大的贡献，这就是使贪婪构造有效的原因。

 ## 边缘情况

 当 n = 1 时，解决方案必须正确处理 x = 1 和 x = -1。 该算法计算 S = 1。对于 x = 1，D = 0，因此不会发生翻转，输出为 +0+1。 对于 x = -1，D = 2，因此目标 = 1，并且由于 1 ≤ 目标，我们翻转数字 1，产生 +0-1，这符合要求。 

当 x = S 时，算法认为 D = 0 并保留所有符号为正。 这可确保表达式折叠为总和，而无需任何不必要的操作。 

当 x = -S 时，D 变为 2S，因此目标为 S。贪婪循环将每个数字从 n 翻转到 1，每个数字恰好消耗整个目标一次。 这会产生所有负号，匹配最小可能的总和。
