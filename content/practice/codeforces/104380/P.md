 ## 解决方案
 ## 问题理解

 地下城是一条直线，骑士从0位置走到D位置，头也不回。 沿着这条路有两种遭遇：怪物和商店，每种都放置在固定的位置。 每个怪物都有所需的强度，如果骑士在到达怪物时太弱，则会受到惩罚。 每个商店都会提供一种药水，可以将骑士的力量提升到固定值，购买也需要金币。 

重要的行为是，骑士的力量只会增加，而且只有当他购买药水时。 药水不会与之前的药水叠加，而是简单地将他的强度设置为药水的级别（如果该级别高于他当前的级别）。 怪物不会改变力量； 他们只会在当前实力不足的情况下才会施加成本。 

目标是决定购买哪些药水（如果有），以及支付哪些怪物来绕过，从而使总硬币成本最小化。 

限制很大，怪物数量最多为10万个，商店最多为10万个，仓位最多可达10^9。 这立即排除了任何尝试沿着路径逐步模拟移动或独立地重新计算每个事件的成本的方法。 在 2 秒限制下，针对事件或候选状态的二次策略也会失败。 解决方案必须将问题简化为更接近排序加上线性或对数处理的问题。 

一个微妙的点是，除了在线订购之外，怪物和商店的位置实际上并不相互作用。 由于除了“骑士是否已经在怪物之前通过商店”之外，没有任何因素取决于时间，并且强度不会减少，因此确切的空间顺序不会影响最优成本结构。 这是许多错误方法都忽略的一个关键简化。 

一种常见的失败案例源于假设药水选择以动态方式依赖于早期怪物。 例如，如果一个骑士很早就遇到了一个弱怪物并决定付费而不是升级，那么天真的贪婪者可能会错过稍后的廉价升级会在全球范围内更好。 另一个失败案例是尝试在维持多个可能的当前强度的同时模拟旅程，这很快就会爆炸，因为强度可以采用最多 10^9 的许多值。 

具体的边缘情况是，所有怪物都很强大，并且除了一种后期强力药水外，所有药水都很昂贵。 任何贪婪的人购买早期的小升级可能会比简单地支付所有罚款直到最终升级更糟糕。 

## 方法

 暴力策略会尝试商店的每个子集，并模拟购买药水的每种选择的旅程。 对于每个选定的子集，我们将扫描所有怪物，并在力量不足时对惩罚进行求和。 这原则上是正确的，因为它直接评估每种可能的策略，但子集的数量为 2^m，即使 m = 40 也是完全不可行的，更不用说 100000 了。即使限制为单一最佳药水，仍然会留下与怪物的交互，每个候选者需要 O(n)。 

关键的观察结果是，药水行为仅由达到的最大水平决定，而不是由购买顺序决定。 如果骑士最终的力量为L，那么任何等级最高为L的药水都是无关紧要的，任何高于L的药水只有在购买一次作为定义升级时才能被考虑。 这将状态空间从指数子集折叠为对可能的最终强度值的简单选择。

一旦理解了这一点，问题就干净地分解为两个独立的部分。 其中一个部分是确定达到给定最终强度 L 的最佳成本，这仅取决于提供等级 L 的商店。另一个部分是计算如果我们有强度 L，我们要为怪物支付多少费用，这仅取决于每个怪物所需的强度是否超过 L。 

独立性至关重要：怪物不会影响我们应该购买哪种药水，而药水也不取决于怪物的排序。 这使我们能够独立评估每个候选 L 并将两个成本贡献结合起来。 

为了提高效率，我们预先计算了按所需强度排序的怪物成本，从而可以快速查询给定 L 所适用的总惩罚是多少。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集的暴力破解 | O(2^m·n) | O(2^m·n) | O(1) | O(1) | 太慢了|
 | 评估每个强度级别+预处理| O((n + m) log n) | O((n + m) log n) | O(n + m) | 已接受 |

 ## 算法演练

 我们将问题转化为评估所有有意义的最终强度值并计算每个值的最佳成本。 

1.从商店中提取所有候选强度值，并且还包括强度0作为没有购买药水的基线情况。 这些代表了骑士可能最终拥有的所有可能的最终力量。 
2.对于每个强度值L，确定获得它的最佳成本。 如果有多个商店提供相同的L，我们就取其中成本最低的。 如果 L 为 0，则成本为 0，因为没有进行购买。 这是有效的，因为购买药水只与它的最终等级有关，中间升级毫无帮助。 
3. 根据所需强度对所有怪物进行排序 h。 除此之外，计算它们的惩罚成本 f 的前缀总和，以便我们可以快速查询任何怪物后缀的总惩罚。 
4. 对于给定的候选强度 L，我们要计算所需强度超过 L 的怪物的总成本。这相当于将 h > L 的怪物的所有 f 相加。对排序后的 h 数组使用二分查找，找到第一个没有被 L 击败的怪物，并取相应的后缀和。 
5.固定L的总成本是L的最佳商店成本和L的怪物惩罚成本之和。 
6. 我们计算每个候选 L 的值并返回所有候选值中的最小值。 

关键的实现细节是我们从不模拟沿路径的移动。 位置 a_i 和 b_i 是不相关的，因为它们只影响排序，而不影响可行性或成本累积。 

### 为什么它有效

 该算法依赖于这样一个不变量：骑士的力量完全由单个标量值来描述，该标量值只会增加并且与空间顺序无关。 任何策略都可以通过选择最终强度 L 并支付一次有效升级来实现它来表示。 一旦 L 固定，所有怪物都会根据 h_i 是否超过 L 独立地表现为免费或付费遭遇。这消除了地牢中不同点决策之间的所有耦合，将顺序优化转变为小型离散集上的静态最小化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    D, n, m = map(int, input().split())

    monsters = []
    for _ in range(n):
        a, h, f = map(int, input().split())
        monsters.append((h, f))

    shop_best = {}
    candidates = [0]

    for _ in range(m):
        b, l, w = map(int, input().split())
        if l not in shop_best:
            shop_best[l] = w
        else:
            shop_best[l] = min(shop_best[l], w)

    for l in shop_best:
        candidates.append(l)

    candidates = list(set(candidates))
    candidates.sort()

    monsters.sort()  # sort by h
    hs = [h for h, f in monsters]
    fs = [f for h, f in monsters]

    # suffix sum of f
    suf = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suf[i] = suf[i + 1] + fs[i]

    def monster_cost(L):
        # first index with h > L
        lo, hi = 0, n
        while lo < hi:
            mid = (lo + hi) // 2
            if hs[mid] <= L:
                lo = mid + 1
            else:
                hi = mid
        return suf[lo]

    ans = float('inf')

    for L in candidates:
        cost_shop = shop_best.get(L, 0)
        cost_mon = monster_cost(L)
        ans = min(ans, cost_shop + cost_mon)

    print(ans)

if __name__ == "__main__":
    main()
```代码首先读取怪物并将商店信息压缩到地图中，该地图仅保留达到每个强度级别的最便宜的方式。 这已经足够了，因为只有达到的最大力量才重要。 

怪物按照所需的强度进行排序，以便我们可以使用二分搜索将它们分成那些被击败的怪物和那些不适合任何候选 L 的怪物。然后，后缀和数组允许对超出该分割点的所有怪物的总惩罚进行恒定时间计算。 

每个候选人的实力都是独立评估的。 最终的答案是商店购买成本加上怪物惩罚的最低组合成本。 

一个常见的微妙之处是确保将强度 0 作为候选包含在内。 如果没有它，不购买药水是最佳选择的情况将被完全错过。

 ## 边缘情况

 一个关键的边缘情况是没有药水值得购买。 在这种情况下，唯一的候选强度为 0，并且算法正确地计算了所有怪物惩罚的总和，因为每个怪物的 h_i > 0。 

另一个微妙的情况是多家商店提供相同的实力。 该算法正确地将它们压缩为每种强度的单一最佳成本，从而防止多算或错误的多次购买。 

另一种情况是存在一种非常强力但昂贵的药水。 算法仍然会考虑它，因为它包含在候选集中，如果它减少了足够的怪物惩罚，它可能会主导所有中间选择。
