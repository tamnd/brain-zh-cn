 ## 解决方案
 ## 问题理解

 我们得到一个学生的考试成绩序列，每个成绩都是 0 到 100 之间的整数。任务是生成该序列的清理版本，其中删除低于 60 的每个成绩，同时保持剩余成绩的相对顺序与原始列表中完全相同。 

输入本质上是一个列表转换问题：我们扫描列表一次，然后针对每个元素决定它是保留到输出中还是被丢弃。 除了基于阈值的过滤之外，元素之间没有重新排序、没有聚合、也没有交互。 

对等级数量的限制（最多 100,000）立即排除了任何重复移动列表内元素或执行嵌套扫描的方法。 在迭代 Python 列表时从 Python 列表中删除元素的简单实现可能会退化为二次行为，因为每次删除都会导致元素发生移动。 对于 100,000 个元素，这种行为在 1 秒的限制下会太慢。 唯一安全的方向是输出的单遍构造。 

边缘情况主要是结构性的而不是数字性的。 如果所有成绩均低于 60，则输出为空，并且不应打印任何内容。 如果所有成绩均为 60 或以上，则输出与输入完全匹配。 打印空结果时经常会出现一个微妙的错误：某些实现意外地打印了额外的换行符或根本无法生成输出。 如果尝试使用索引删除进行就地过滤，则会出现另一个问题，这可能会由于索引移位而跳过元素。 例如，在`[59, 58, 61]`，删除 59 将 58 移至其位置，并且基于索引的循环可能会跳过对其进行检查，具体取决于迭代的结构方式。 

## 方法

 思考这个问题最直接的方法是从字面上模拟这个过程：扫描列表并删除 60 以下的任何元素。从抽象意义上讲，这是正确的，因为它完全符合规范。 然而，在 Python 列表中实现删除的成本很高。 每次删除都会将所有后续元素向左移动一位，在最坏的情况下每次删除的成本为 O(n)。 如果大多数元素都很小，我们可能会删除几乎所有条目，从而导致 O(n²) 行为。 

结构上的见解是，如果我们从不就地改变列表，则删除是不必要的。 相反，我们可以构建一个新列表并仅附加有效元素。 这会将每个元素的处理成本转换为 O(1)，因为追加到列表的时间是摊销的常量。 问题简化为单个线性扫描，我们在其中测试条件并决定是否向前复制元素。 

其高效工作的原因是输出顺序与保留元素的输入顺序相同。 决策之间不存在依赖性，因此每个等级都可以独立评估。 一旦我们停止尝试保留原始容器，而是构建一个经过过滤的容器，复杂性就会从潜在的二次型崩溃为线性型。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 迭代期间就地移除 | O(n²) | O(1) | O(1) | 太慢了|
 | 构建过滤列表| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取等级数`n`。 这定义了我们将检查一次的值数量。 
2.初始化一个空列表`result`这将存储通过阈值检查的所有成绩。 
3. 迭代每个`n`从输入中读取的成绩。 
4. 对于每个年级，将其与 60 进行比较。 
5. 如果成绩至少为 60，请将其附加到`result`。 否则，完全忽略它。 
6. 处理完所有等级后，打印每个值`result`按照它们添加的顺序在自己的行上。 

关键的设计选择是我们永远不会修改输入序列。 每个决策都是单个元素的本地决策，因此我们避免了可能影响未来迭代的任何副作用。 

### 为什么它有效

 在扫描的每一步中，`result`包含到目前为止看到的至少 60 分的所有成绩的序列，其顺序与输入中出现的顺序相同。 当我们处理一个新的成绩时，如果它低于 60，我们要么丢弃它，要么如果它有效，我们将它附加到末尾。 这既保证了过滤的正确性，又保证了排序的稳定性。 由于每个元素都被检查一次并且其包含仅取决于其自身的值，因此后续操作不能使先前的决定无效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    result = []

    for _ in range(n):
        x = int(input())
        if x >= 60:
            result.append(x)

    sys.stdout.write("\n".join(map(str, result)))

if __name__ == "__main__":
    main()
```该解决方案使用快速输入`sys.stdin.readline`因为用标准读取多达 100,000 行`input()`可能会带来不必要的开销。 每个成绩在读取后立即处理，并且仅存储有效成绩。 

一个微妙的实现细节是最终的输出构造。 我们不是逐行打印，而是将所有有效整数连接到一个字符串中。 这避免了重复的 I/O 调用，在严格的限制下，这在 Python 中可能会很慢。 

另一点是处理以下情况`result`是空的。 连接操作自然会产生一个空字符串，它与所需的输出格式匹配，没有额外的行。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个等级读一次、检查一次 |
 | 空间| O(k) | 仅存储 ≥ 60 的成绩，其中 k ≤ n |

 该算法随等级数量线性扩展，这是最佳的，因为每个输入元素必须至少检查一次。 n 高达 100,000，这可以轻松满足时间和内存的限制。

 ## 边缘情况

 当所有成绩均低于 60 分时，例如`10, 20, 30`，该算法仍然迭代每个值并且根本不附加任何内容。 结果仍然是一个空列表，并且连接操作会生成一个空字符串，它正确匹配所需的输出格式，而无需额外的行。 

当所有成绩均有效时，例如`60, 80, 100`，每个元素都满足条件并按顺序附加。 该算法有效地成为输入的直接副本，从而确认不会发生意外的转换。 

当值在阈值附近交替时，例如`59, 60, 58, 61`，每个决定都是独立的。 扫描显示拒绝的值不会影响以后的接受，并且排序完全按照要求保留。
