 ## 解决方案
 ## 问题理解

 我们从网格中的原点开始，想要到达目标坐标$(x, y)$。 从当前的任何位置开始，兔子有三种可能的移动方式：它可以向右移动一步以获取成本$A$, 成本又提高了一步$B$，或者它可以将两个坐标缩放两倍以降低成本$C$。 目标是准确达到$(x, y)$以最小的总成本。 

关键的困难在于加倍移动不依赖于网格步骤，而是同时改变两个坐标的比例。 这引入了在以单位步骤逐渐构建目标坐标或构建较小版本并重复加倍之间的权衡。 

约束允许最多$10^4$坐标高达的测试用例$10^9$。 这立即排除了任何对坐标的状态空间搜索或任何依赖于值的动态规划$x$和$y$直接地。 解决方案必须将每个测试用例简化为对数甚至常数时间推理。 

当将问题视为两个独立的一维优化时，会出现一个天真的陷阱。 例如，如果我们单独决定如何构建$x$和$y$，我们会忽略这样一个事实：加倍同时影响两者，有时会导致过冲然后向后“塑造”结果的成本更低，这是不允许的，因为只存在增量和缩放。 

另一个微妙的问题是假设当$C < A + B$。 这还不够，因为提前或推迟加倍会改变仍然需要多少单位增量。 例如，达到$(4, 4)$从$(0,0)$可能更喜欢不同的顺序，具体取决于我们是否构建$(2,2)$首先或到达$(4,0)$和$(4,4)$分别地。 

当出现第三种边缘情况时$x = 0$或者$y = 0$。 那么一个坐标就无关紧要了，并且通过加倍操作将问题简化为一维，该操作可能有用也可能没用，具体取决于它是否比重复的单元步骤更便宜。 

## 方法

 暴力方法会将每个位置视为一个状态，并使用 BFS 或 Dijkstra 探索所有可能的移动序列。 各州$(x, y)$可以过渡到$(x+1, y)$,$(x, y+1)$， 或者$(2x, 2y)$。 虽然原则上是正确的，但该图是巨大的。 甚至将自己限制在以下值$10^9$，双重边缘导致反向指数分支，任何最短路径搜索将立即变得不可行。 可到达状态的数量随着坐标的大小而增长，使得任何直接遍历都不可能$T = 10^4$。 

关键的结构观察是，如果我们从$(x, y)$。 我们可以考虑减少目标，而不是向前构建：如果两者都$x$和$y$是偶数，我们可能通过加倍操作到达$(x/2, y/2)$。 否则，必须使用单位增量至少达到一个坐标。 

这表明了一种贪婪的向后缩减策略：反复决定是“撤消”加倍还是“撤消”单位步骤更好。 消除双倍成本$C$，但只有当两个坐标都是偶数时才有可能。 否则，我们必须从其中减一$x$或者$y$, 支付$A$或者$B$。 每个步骤的决策都变得局部且最优，因为任何有效序列中的最后一个操作都是由奇偶校验约束确定的。 

我们不断地缩小问题直到达到$(0,0)$。 这会产生每个测试用例的对数步数，以中的位数为界$x$和$y$。

 ## 算法演练

 我们从$(x, y)$到$(0, 0)$，始终选择可能产生当前状态的最后一个操作。 

1. 如果两者都$x = 0$和$y = 0$，我们完成了。 迄今为止累计的总成本就是答案。 
2. 如果两者都$x$和$y$是偶数，考虑最后一步可能是加倍操作。 我们比较一下它的成本$C$其成本是使用先前规模的两个独立单元操作来达到相同的状态。 如果加倍更便宜或相等，我们将两个坐标除以 2 并相加$C$到答案。 此步骤显着压缩状态，同时尊重加倍操作的结构。 
3. 如果至少有一个坐标是奇数，则最后一步不可能加倍。 我们必须撤消单位移动。 我们比较是否减少$x$或减少$y$更便宜，即是否$A$或者$B$较小。 我们从单位成本较小的坐标中减去。 这确保了我们不会为造成不对称的最后一步支付不必要的费用。 
4. 重复直到两个坐标都为零。 

关键的微妙之处在于奇偶性会影响最后一步的结构。 如果一个状态是偶偶的，那么它是来自加倍还是来自长序列的单位移动是不明确的，但任何最佳解决方案都会选择该规模的两种可能性中更便宜的一个。 如果状态不是偶数，加倍在结构上是不可能的，因此最后一次移动必须是一个坐标上的单位增量。 

### 为什么它有效

 每个有效路径从$(0,0)$到$(x,y)$可以通过查看其最终操作来唯一地分解。 如果$(x,y)$是偶偶，最终的操作要么是加倍$(x/2,y/2)$或独立地将两个坐标构建为其当前奇偶校验状态的一系列单元步骤。 由于单位步骤和加倍是达到这种奇偶校验配置的唯一方法，因此在本地比较它们的成本会产生最佳的最后转换。 重复这个推理可以归纳地保证每个缩减步骤都保留最优子结构，因此累积成本与全局最小值匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_one(x, y, A, B, C):
    ans = 0
    while x > 0 or y > 0:
        if x % 2 == 0 and y % 2 == 0:
            if C < A + B:
                ans += C
                x //= 2
                y //= 2
            else:
                if x == 0:
                    ans += B
                    y -= 1
                elif y == 0:
                    ans += A
                    x -= 1
                else:
                    if A <= B:
                        ans += A
                        x -= 1
                    else:
                        ans += B
                        y -= 1
        else:
            if x % 2 == 1:
                ans += A
                x -= 1
            else:
                ans += B
                y -= 1
    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        x, y, A, B, C = map(int, input().split())
        out.append(str(solve_one(x, y, A, B, C)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该方案直接实现了后向约简。 循环继续直到两个坐标都达到零，确保终止，因为每个步骤都严格减少$x+y$或将两个值减半。 

最微妙的部分是偶偶盒。 当两个坐标都可以被二整除时，代码会比较应用加倍步骤的成本与支付单位减少的成本。 比较使用$C < A + B$作为阈值，因为撤销加倍对应于先前独立构建的两半。 如果加倍没有好处，算法会回退到从更便宜的坐标中减去一个单位。 

奇数坐标情况强制单位递减，因为之前的加倍不可能产生奇数坐标。

 ## 边缘情况

 当$(x,y) = (0,0)$，循环永远不会执行，并且答案正确为零，因为不需要任何操作。 

当一个坐标为零时，例如$(0, k)$，该算法从不考虑加倍，因为偶偶条件仅部分有用。 它反复从非零坐标中减去，支付$B$每次都匹配唯一可行的构建路径。 

当两个坐标都是 2 的幂且$C$很小，重复减半会在每一步立即触发，以对数时间将状态降低到零，并精确累积重复加倍操作的成本。 

当成本严重不平衡时，例如$A \ll B$，该算法始终通过更便宜的轴耗尽更大成本的坐标，确保没有步骤支付超过解决奇偶校验约束所需的费用。
