 ## 解决方案
 ## 问题理解

 我们对两个正整数重复应用相同的运算。 在每一步中，我们都会从较大的值中减去较小的值。 一旦一个数字变为零，该过程就会停止。 任务是计算每对执行了多少次减法运算。 

例如，从`(4, 17)`:`(4,17) → (4,13) → (4,9) → (4,5) → (4,1) → (3,1) → (2,1) → (1,1) → (0,1)`该序列包含`8`运营。 

输入最多包含`1000`独立对，每个值可以大到`10^9`。 每次操作执行一次减法的直接模拟可能会变得非常慢。 考虑`(1, 10^9)`。 该进程执行了近十亿次操作，因为较大的数字仅减少了`1`每次。 任何从字面上模拟每次减法的算法都会超出时间限制。 

该过程的结构与最大公约数的欧几里得算法非常相似。 我们可以使用整数除法来计算一次发生的减法次数，而不是每次迭代减一次。 

有一些容易被忽略的极端情况。 

当数字相等时，一次操作会立即将一个值变成零。 例如：```
5 5
```答案是`1`， 不是`5`。 粗心的实现会反复进行减法直到较大的值变小，可能会意外地过度计数。 

一个数字远大于另一个的数字对是另一个陷阱。 例如：```
1 1000000000
```正确答案是`1000000000`。 一个简单的循环需要十亿次迭代。 

当较大数字是较小数字的精确倍数时，会出现另一种微妙的情况：```
3 12
```顺序是：`(3,12) → (3,9) → (3,6) → (3,3) → (0,3)`答案是`4`。 仅使用余数运算而不计算发生了多少次减法会丢失信息。 

## 方法

 最直接的解决方案是完全按照描述模拟该过程。 在每一步中，比较两个数字并从较大的数字中减去较小的数字。 每次减法后增加答案。 

这是有效的，因为规则是确定性的。 每次操作都会减少两个数字的总和，因此该过程最终终止。 

问题是性能。 在最坏的情况下，比如`(1, 10^9)`，算法执行十亿次迭代。 这远远超出了一秒的时间限制。 

关键的观察是重复的减法相当于除法。 

假设我们有`(a, b)`和`a < b`。 反复减法`a`从`b`继续直到`b < a`。 执行减法的次数恰好是`b // a`，剩余值变为`b % a`。 

例如：`(4,17)`减法`4`反复：`17 → 13 → 9 → 5 → 1`这花了`17 // 4 = 4`操作，新值是`17 % 4 = 1`。 

因此，我们可以一步直接跳转到结果，而不是执行四个单独的操作。 

这将该过程转换为欧几里得算法。 每次迭代将一个数减至余数，并通过整数除法累加减法总数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O（答案）| O(1) | O(1) | 太慢了 |
 | 最佳 | O(log(最大(a,b))) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 
2. 对于每对`(a, b)`, 初始化`ans = 0`。 
3. 当两个数字均为正数时，请执行以下操作：

 如果`a < b`， 然后`b`可以减去`a`确切地`b // a`之前变得小于`a`。 

添加`b // a`到答案并替换`b`和`b % a`。 
4. 否则，如果`a >= b`， 然后`a`可以减去`b`确切地`a // b`之前变得小于`b`。 

添加`a // b`到答案并替换`a`和`a % b`。 
5. 继续下去，直到一个数字变为零。 
6. 打印累计答案。 

### 为什么它有效

 在每个阶段，该过程都会在一次跳转中执行最大可能数量的相同减法。 

如果`b > a`, 反复相减`a`从`b`在数学上等同于：```
b = b - a * (b // a)
```剩余的值正好是`b % a`，执行的操作数为`b // a`。 

该算法保留了精确的序列计数，同时跳过不必要的中间状态。 由于每次迭代都会用严格较小的余数替换一个值，因此数字会迅速减少，就像欧几里得算法一样。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    a, b = map(int, input().split())
    
    ans = 0
    
    while a > 0 and b > 0:
        if a < b:
            ans += b // a
            b %= a
        else:
            ans += a // b
            a %= b
    
    print(ans)
```该解决方案严格遵循欧几里得算法结构。 

当两个数字都保持正值时，循环将继续。 一旦一个值变为零，就不可能再相减，所以这个过程自然结束。 

最重要的细节是在取余数之前先加上商。 商表示跳过了多少个单独的减法运算。 忘记此步骤将仅计算最终的 gcd 过程，而不是总操作计数。 

使用模是安全的，因为重复减法和模产生相同的余数。 模版本只是将许多运算压缩为一个算术步骤。 

Python 整数处理的值可达`10^9`很容易，因此不存在溢出问题。

def solve():

 ## 边缘情况

 考虑相同的数字：```
5 5
```执行轨迹：

 | 一个 | 乙| 添加操作 | 总计 |
 | ---| ---| ---| ---|
 | 5 | 5 | 1 | 1 |
 | 0 | 5 | 停止| 1 |

 该算法正确计算单个减法，因为`5 // 5 = 1`。 

现在考虑一个巨大的不平衡：```

```执行轨迹：

 | 一个 | 乙| 添加操作 | 总计 |

 | 1 | 1000000000 | 1000000000 | 1000000000 |
 | 1 | 0 | 停止| 1000000000 |

 优化后的方法只需一次迭代即可完成，而不是十亿次迭代。 

最后，考虑一个精确倍数：```

 | 一个 | 乙| 添加操作 | 总计 |

 商正确捕获所有重复的减法。 粗心的实现仅使用模而不添加商将错误地返回零运算。
