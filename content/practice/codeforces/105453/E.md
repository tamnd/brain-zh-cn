 ## 解决方案
 ## 问题理解

 我们拥有一个完全指定的岛屿网络，其中每个岛屿都可以通过在其上建造发电机来供电，或者通过传输线连接到最终拥有发电机的其他岛屿来供电。 每个岛屿都有建造发电机的直接成本，每对岛屿都有连接输电线路的成本。 

目标是同时决定哪些岛屿应配备发电机以及应修建哪些输电线路，以便每个岛屿都能供电，同时最大限度地降低建设总成本。 

重新表述这一要求的一种有用方法是，每个岛屿都必须有一条通往至少一个安装了发电机的“源”岛的路径。 该源可以是其本身，也可以是通过已建立的连接可到达的另一个岛屿。 

输入大小高达 1000 个岛屿，并且成本结构很密集，因为每对岛屿都有定义的连接成本。 这立即排除了任何试图显式枚举岛屿子集来放置发电机的方法，因为子集的数量呈指数增长。 甚至子集上的二次或三次解也是不可能的。 

如果有 1000 个节点和一个完整的图，自然目标复杂度约为 O(N^2) 或 O(N^2 log N)。 任何涉及 O(N^3) 或更糟的事情都可能会超时。 这强烈暗示我们应该将问题重新解释为图优化问题而不是组合选择问题。 

当人们试图分别处理生成器放置和边缘构造时，就会出现一种幼稚推理的微妙失败案例。 例如，如果我们首先贪婪地在廉价岛屿上构建生成器，然后使用最短边连接所有内容，我们可能会错过更好的全局结构，其中稍微昂贵的生成器放置可以避免许多昂贵的边。 

## 方法

 一种强力的解释是选择一个岛屿的子集来放置发电机，然后对于其余的岛屿计算使用传输线将它们连接到至少一个发电机的成本。 对于每个子集，这可以简化为加权图上的最短连接问题，但我们需要尝试所有岛屿子集，这已经引入了 2^N 种可能性。 即使一个子集的计算连通性为 O(N^2)，总工作量也会呈指数级增长，并且在 N = 1000 时完全不可行。 

关键的观察结果是，问题的结构与构建最小生成树完全相同，但有一个额外的“虚拟选项”，即支付节点成本而不是边缘成本。 如果我们引入一个假想的代表外部电源的超级节点，那么将岛屿 x 直接连接到该超级节点的成本为 p(x)，连接两个岛屿 x 和 y 的成本为 c(x,y)。 一旦以这种方式查看，每个有效的解决方案都对应于 N+1 个节点的生成树，其中超级节点恰好连接到托管发电机的那些岛屿。 

因此，最佳解决方案就是该展开图的最小生成树。 我们可以将每个节点的连接成本初始化为其生成器成本，然后使用传输线逐步放松，从而将其效果纳入 Prim 算法中，而不是显式构造额外节点。 

蛮力失败是因为它将生成器放置视为单独的组合决策，而正确的结构表明这两个决策统一为单个生成树问题中的边缘选择。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对生成器子集的暴力破解 | O(2^N · N^2) | O(2^N · N^2) | O(N^2) | O(N^2) | 太慢了|
 | 最小生成树（Prim）| O(N^2) | O(N^2) | O(N^2) | O(N^2) | 已接受 |

 ## 算法演练

我们将问题重新解释为计算 N 个岛屿上的最小生成树，其中每个岛屿还与虚拟电源有隐式连接，其成本等于其发电机成本。 

1. 我们初始化一个距离数组，其中 dist[x] 表示将岛屿 x 连接到已构建的网络的最便宜的已知方法。 最初，这只是在 x 上构建生成器的成本。 
2. 我们维护一个已访问数组来跟踪哪些岛屿已永久添加到网络中。 
3.我们反复选择当前dist值最小的未访问过的岛屿。 此选择对应于在那里建造发电机或通过先前添加的岛屿以最佳方式连接它。 
4. 一旦我们选择了一个岛屿，我们将其距离值添加到总成本中并将其标记为已访问。 
5. 添加岛屿 u 后，我们尝试使用传输线路成本 c(u, v) 来改善每个其他未访问岛屿 v 的连接成本。 如果 c(u, v) 比当前的 dist[v] 便宜，我们就更新它。 
6. 我们重复这个过程，直到所有岛屿都被包括在内。 

关键思想是 dist[v] 始终代表将 v 连接到不断增长的网络的最便宜的方式，无论是直接构建生成器还是通过已连接的岛屿连接它。 

### 为什么它有效

 在任何一步，访问的岛屿集合都会形成部分构建的最优网络。 对于每个未访问的岛屿，dist[v] 是将其连接到该集合的最小成本边，包括到虚拟源的隐式边。 选择最小的 dist 值正是最小生成树的割属性：穿过已访问节点和未访问节点之间的割的最便宜的边必定属于某个最优解。 这保证了每次添加都是局部最优且全局一致的，从而防止循环并确保总成本最小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [list(map(int, input().split())) for _ in range(n)]

    dist = [0] * n
    vis = [False] * n

    for i in range(n):
        dist[i] = a[i][i]

    total = 0

    for _ in range(n):
        u = -1
        best = 10**18

        for i in range(n):
            if not vis[i] and dist[i] < best:
                best = dist[i]
                u = i

        vis[u] = True
        total += dist[u]

        for v in range(n):
            if not vis[v]:
                if a[u][v] < dist[v]:
                    dist[v] = a[u][v]

    print(total)

if __name__ == "__main__":
    solve()
```该解决方案使用针对密集图优化的 Prim 算法的直接实现。 矩阵`a`可重复用于对角线上的发电机成本和非对角线的输电成本。 数组`dist`从在每个岛上建造发电机的成本开始，这与将每个节点连接到虚拟电源的解释相匹配。 

主循环反复选择连接成本最小的未访问过的岛屿。 这是通过简单的线性扫描完成的，在 N ≤ 1000 的情况下这是可以接受的。选择一个岛后，我们使用矩阵值松弛其所有边缘。 

一个常见的微妙之处是初始化`dist`正确。 如果我们从零或无穷大开始，我们就会错误地将算法偏向于总是选择传输线或总是选择发电机。 使用对角线条目可确保两个选项得到统一处理。

 ## 边缘情况

 一个关键的边缘情况是所有岛屿单独供电比连接更便宜。 对于像对角矩阵这样具有较小值和非常大的非对角项的输入，算法不应该选择传输边。 以对角线值开始 dist 可确保每个岛屿有效地“自供电”，除非出现更便宜的连接，但在本例中并非如此。 

另一种情况是输电成本都比发电机便宜。 例如，对角线条目较大，而非对角线条目较小。 该算法首先选择一个岛屿，然后快速将低边缘成本传播到所有其他岛屿，从而形成一个连接链，取代除第一个隐式决策之外的所有生成器决策。 最终成本成为仅使用传输边的生成树的成本。 

最后一种微妙的情况是，当存在混合模式时，生成器对于一个区域是最佳的，而边缘则主导另一个区域。 Prim 算法中基于切割的选择确保每个决策都是当前边界的本地决策，因此区域根据成本自然地分离，而不需要显式的聚类逻辑。
