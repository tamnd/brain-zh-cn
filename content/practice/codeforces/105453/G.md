 ## 解决方案
 ## 问题理解

 我们得到了一系列按预定起飞时间排序的航班。 每个航班都有一个理想的使用跑道的时间，如果允许在该时间起飞，它会提供付款，如果不允许，则会施加罚款。 

由于机场只剩下一条跑道，只有部分航班能够在接近计划时间的情况下起飞。 如果航班准时起飞，就会带来积极的回报。 如果未选择，则航班将被推迟，并会产生负值，因为航空公司会因延误而获得补偿。 

操作限制是，每当我们选择让航班准时起飞时，我们必须确保在下一次选择的起飞之前至少经过 T 个时间单位。 这将问题转化为选择尊重间距限制的航班子集，同时最大化总利润，其中每个选定的航班给出一个值，每个跳过的航班给出另一个值。 

输出是决定哪些航班准时起飞、哪些航班延误后可实现的最大总利润。 

这些约束清楚地表明 N 可以大到一百万，这立即排除了任何二次甚至对数平方动态规划。 检查所有航班对或执行按州进行大量搜索的解决方案将超出时间限制。 关键要求是对排序的航班进行本质上线性或近线性的扫描。 

天真的解释也会忽略时间表限制仅适用于选定的航班之间，而不适用于所有航班。 这种区别使得贪婪或每次飞行的本地决策不正确。 

当所有航班的时间都接近时，就会出现微妙的边缘情况。 例如，如果 T 很大并且所有 t_i 都紧密排列，我们可能只会选择一个航班。 总是选择最佳即时增益 b_i - c_i 的天真的贪婪策略可能会失败：

 输入：```
3 10
1 100 -1
2 90 -1
3 80 -1
```贪婪的选择可能会因为最高增益而选择第一个航班，但在其他结构化情况下，它可能会错过如果时间允许的话稍后的组合会产生更好的间距。 真正的约束将跨指数的决策耦合起来。 

另一个边缘情况是，如果 c_i 比其他航班更接近零，则延迟实际上对某些航班有利。 由于 c_i 为负，忽略结构并将所有跳过的航班视为零成本将完全破坏正确性。 

## 方法

 第一个自然的尝试是独立决定每个航班是准时还是延误。 这会立即失败，因为由于 T 间距限制，乘坐航班会影响未来可以乘坐的航班。 任何枚举满足间距的所有航班子集的尝试都会导致指数级的复杂性，因为每个航班都可以被选择或跳过。 

一种更结构化的强力方法是按顺序处理航班，并且对于每个航班，在跟踪最后选择的时间的同时递归地决定是否乘坐该航班。 这会产生一个状态空间，其中每个步骤分支为两个选择，并且在最坏情况下状态数量大致增长为 2^N。 即使修剪无效的调度也没有足够的帮助，因为当时间稀疏时，有效的子集仍然非常多。 

关键的观察结果是，无论调度决策如何，跳过航班的贡献都是固定的。 如果未选择，每个航班都会贡献 c_i。 如果我们从所有航班延误的基线开始，则总数就是所有 c_i 的总和。 唯一真正的决定是我们将哪些航班从延误升级为准点，每次升级都会带来 b_i - c_i 的利润增加。 

这将问题转化为选择航班的子集，每个航班都有一个重量增益，并受到由时间确定的索引的间距约束。 一旦以这种方式重新构建，该结构就成为排序列表上的经典加权间隔调度问题，其中兼容性是由时间间隙而不是任意间隔定义的。 

因为航班已经按时间排序，对于每个航班 i，我们只需要知道它之前的最后一个航班 j，这样 t_j + T <= t_i。 然后我们决定是否乘坐 i 航班并将其增益添加到 j 之前的最佳解决方案之上，或者跳过它。 

这直接导致了动态规划公式，可以使用两指针技术在线性时间内进行评估。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对选择的强力递归 O(2^N) | O(2^N) | O(N) | 太慢了|
 | DP 与前驱搜索 | O(N) | O(N) | 已接受 |

 ## 算法演练

 我们首先将每个航班转换为一个值，该值表示按时提供航班而不是延误航班的效果。 该值为 b_i - c_i。 我们还将基线贡献计算为所有 c_i 的总和。 

接下来，我们按时间递增顺序处理航班并构建动态规划表。 

1. 将每次飞行的增益计算为 b_i - c_i。 这隔离了选择航班的决策影响。 
2.维护一个指针j，该指针j跟踪可以在当前航班之前安排的最新航班，而不违反T间隙约束。 
3. 对于每个航班 i，在 t_j + T <= t_i 成立的情况下，尽可能提前 j。 由于时间已排序，j 仅在整个运行过程中向前移动，从而保持流程线性。 
4. 将 dp[i] 定义为使用前 i 次飞行可实现的最佳增益。 对于每个 i，我们有两个选择：忽略航班 i 并保留 dp[i-1]，或者乘坐航班 i 并将其增益添加到 dp[j]。 
5. 将 dp[i] 更新为这两个选择中的最大值。 
6. 处理完所有航班后，将所有 c_i 的基线总和添加到 dp[N] 以恢复全部利润。

正确性取决于这样一个事实：一旦我们确定了所选的航班 i，对早期选择的唯一限制是它们必须在 t_i - T 或之前结束。任何包含 i 的最佳解决方案都必须将其与兼容的早期航班的最佳解决方案结合起来，并且 dp[j] 已经表示该最佳方案。 

dp 状态是完整的，因为它捕获了每个航班前缀的最佳可实现增益，并且由于时间排序的单调性，转换永远不会跳过有效的候选者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    T = int(next(it))

    t = [0] * n
    b = [0] * n
    c = [0] * n

    for i in range(n):
        t[i] = int(next(it))
        b[i] = int(next(it))
        c[i] = int(next(it))

    base = 0
    gain = [0] * n

    for i in range(n):
        base += c[i]
        gain[i] = b[i] - c[i]

    dp = [0] * (n + 1)

    j = 0
    for i in range(1, n + 1):
        ti = t[i - 1]

        while j < i and t[j] + T <= ti:
            j += 1

        take = dp[j] + gain[i - 1]
        skip = dp[i - 1]
        dp[i] = take if take > skip else skip

    print(base + dp[n])

if __name__ == "__main__":
    solve()
```该代码首先读取所有航班并将基线惩罚结构与决策相关组件分开。 dp 数组仅存储相对于“全部延迟”场景的增量改进，这简化了转换。 

指针 j 单调前进，这是确保线性复杂性的关键实现细节。 它永远不会为每个 i 重置，因为兼容性窗口只会随着时间的增加而向前移动。 

一个常见的陷阱是为每个 i 从头开始​​重新计算 j，这会将性能降低到二次时间。 另一个微妙的问题是忘记 dp[j] 指的是最后一个兼容航班之前结束的前缀，不包括 j 本身，这就是为什么指针要小心前进。

```由于 T 较大，所有航班彼此不兼容。DP 最多只能选择一个增益，并且它正确地选择了最佳的单个改进，产生最终答案 -3 + 99 = 96。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        data = sys.stdin.read().strip().split()
        it = iter(data)
        n = int(next(it))
        T = int(next(it))
        if n == 0:
            print(0)
            return

        t = [0] * n
        b = [0] * n
        c = [0] * n

        for i in range(n):
            t[i] = int(next(it))
            b[i] = int(next(it))
            c[i] = int(next(it))

        base = sum(c)
        gain = [b[i] - c[i] for i in range(n)]

        dp = [0] * (n + 1)
        j = 0

        for i in range(1, n + 1):
            ti = t[i - 1]
            while j < i and t[j] + T <= ti:
                j += 1
            dp[i] = max(dp[i - 1], dp[j] + gain[i - 1])

        print(base + dp[n])

    solve()
    return sys.stdout.getvalue().strip()

 ## 边缘情况

 当 T 为零时，每个航班都相互兼容，并且最佳策略变为选择所有航班，因为每个增益都是独立的。 该算法可以处理这个问题，因为 j 总是前进到 i，将 dp 转换转变为正增益的简单累积。 

当T极大时，只能选择一个航班。 在这种情况下，dp 自然会减少到选择所有航班中的最大增益，因为对于所有有效 j，dp[j] 始终为零。 

当所有增益均为负时，dp 永远不会提高到超过零，这意味着最佳策略是延迟每个航班。 这是正确捕获的，因为 dp 仍然为非正且基本成本是不可避免的。 

当航班在时间上极其密集时，指针 j 前进缓慢，算法的行为类似于标准加权调度 DP，始终尊重最新的兼容边界，而无需重新访问较早的航班。
