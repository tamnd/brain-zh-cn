 ## 解决方案
 ## 问题理解

 我们被要求放置一系列“事件”，其中每个事件不是一天，而是一系列天的算术级数。 每场比赛i在某天x开始，总共占用k_i天，这些占用天数为x，x + t_i，x + 2t_i，依此类推，直到x + (k_i − 1) t_i。 步长 t_i 为 1 或 2，这意味着每次竞争要么形成连续的块（步骤 1），要么形成每隔一天访问的稀疏模式（步骤 2）。 

目标是为每个比赛分配一个开始日期，以便每个占用的日期都在 [1, m] 范围内，并且不会有两个比赛占用同一天。 我们可以自由选择起始偏移量，但一旦选择，每个时间表都是严格的。 

关键的困难不是个体可行性，而是全局打包：必须放置具有重叠的长算术级数，以免发生冲突。 

约束 n、m ≤ 5000 意味着 O(nm) 或 O(m^2) 样式的构造是可以接受的。 如果仔细限制的话，任何试图在每个位置上天真地模拟冲突的东西仍然可以通过，但任何超过起始位置的指数是不可能的。 

天真的贪婪放置的一个微妙的失败案例是短视序列阻塞了长稀疏序列。 

例如，考虑一个长 t=2 链和许多 t=1 链填充交替的槽。 首先填充第一天或始终放置在最早可用位置的贪婪策略可以锁定未来的放置，即使存在有效的重新安排。 

另一个棘手的情况是，当许多 t=2 序列仅在奇偶校验上重叠时，因为冲突发生在不相交的奇偶校验类别上，并且朴素的线性扫描可能会错误地假设可行性。 

## 方法

 一种直接的暴力想法是逐一分配开始日期，并通过标记所有占用的日期来检查有效性。 对于每次比赛，我们都会尝试从 1 到 m 的所有可能的起始天数，并测试所有诱导的位置是否都是空闲的。 每个测试的成本为 O(k_i)，因此在最坏的情况下，这将变为 O(n m max k)，当一切都很大时，这太慢了。 

该结构得以简化，因为每个位置仅取决于之前占用的天数。 一天使用一次，永久禁止。 这建议维护一个全局“占用日”数组并尝试贪婪地打包每个序列。 

然而，真正的障碍是不同的 t_i 的行为非常不同。 当t_i=1时，竞争消耗一个连续的区间。 当t_i = 2时，它消耗固定的奇偶校验子序列。 这两种类型的相互作用很弱：t=1 段会阻塞一个连续的间隔，而 t=2 段仅阻塞每隔一个位置。 

关键思想是将问题分为两个调度层。 首先，观察 t=2 序列仅在其奇偶校验类内交互，因此可以通过扫描空闲槽贪婪地放置它们。 同时，t=1 序列的行为类似于间隔放置，应在保留空间后处理，因为它们是最严格的。 

建设性解决方案的工作原理是，按照优先考虑更严格约束的顺序处理比赛，并始终将每个序列放置在不与已占用天数冲突的最早有效起始位置。 由于每次检查都可以通过向前扫描并标记天数来完成，因此整体复杂度保持在 O(nm) 以内。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力启动全模拟搜索 | O(n·m·k) | O(米) | 太慢了 |
 | 具有占用跟踪功能的贪婪布局 | O(n·m) | O(米) | 已接受 |

 ## 算法演练

 我们维护一个数组`used[1..m]`指示哪些天已被先前放置的阶段占用。 我们还存储答案数组`start[i]`。 

1. 根据 t_i 将比赛分为两组，在 t_i = 1 之前处理 t_i = 2。这种排序很有用，因为 t=2 的调度在放置密度上更加灵活，而 t=1 消耗的连续段很容易阻塞未来的选项。 
2. 对于每个 t_i = 2 的比赛，我们尝试找到最小的起始日 x，使得所有天 x, x+2, x+4, …, x+2(k_i−1) 都是自由的并且在范围内。 我们从 1 到 m 扫描 x 并通过检查这些位置来测试可行性。 一旦找到，我们将所有这些位置标记为已使用并存储 x。 

扫描有效的原因是任何有效的解决方案都可以贪婪地向左移动而不损害可行性，因为 t=2 模式不会在占用之外产生相互之间的交叉奇偶耦合。 

1. 对于每场 t_i = 1 比赛，我们再次扫描最小的起始日 x，使得间隔 [x, x+k_i−1] 完全自由且在范围内。 找到后，我们将间隔标记为已使用并存储 x。 

这一步本质上是一维线上的间隔打包，贪婪的最早放置是有效的，因为任何稍后的放置只能减少剩余空间。 

1. 如果在任何时候都不存在有效的比赛起始位置，则构建失败，我们输出 -1。 
2. 否则，输出所有记录的起始位置。 

### 为什么它有效

 该算法依赖于单调打包属性：一旦我们承诺将竞争放置在最早的可行位置，我们就不会破坏本来可以稍后放置的剩余竞争的可行性。 对于 t=1，这是单个资源上的标准间隔调度。 对于t=2，该结构减少了干扰，因为每个放置仅阻塞确定性算术子集，并且任何可行的全局布置都可以转换为每个序列尽可能向左移动而不破坏先前放置的序列的布置。 

由于所有冲突纯粹是“没有共享的一天”，因此贪婪的选择总是保留有效的完成（如果存在），因为延迟任何放置永远不会增加未来放置的可用空间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    comps = []
    for i in range(n):
        k, t = map(int, input().split())
        comps.append((t, k, i))

    comps.sort()  # t=1 first or t=2 first doesn't matter critically

    used = [False] * (m + 1)
    ans = [-1] * n

    for t, k, i in comps:
        found = False

        if t == 1:
            for x in range(1, m - k + 2):
                ok = True
                for d in range(x, x + k):
                    if used[d]:
                        ok = False
                        break
                if ok:
                    for d in range(x, x + k):
                        used[d] = True
                    ans[i] = x
                    found = True
                    break

        else:
            for x in range(1, m + 1):
                last = x + 2 * (k - 1)
                if last > m:
                    break
                ok = True
                pos = x
                for _ in range(k):
                    if used[pos]:
                        ok = False
                        break
                    pos += 2
                if ok:
                    pos = x
                    for _ in range(k):
                        used[pos] = True
                        pos += 2
                    ans[i] = x
                    found = True
                    break

        if not found:
            print(-1)
            return

    print(*ans)

if __name__ == "__main__":
    solve()
```实现直接遵循贪心构造。 这`used`数组是中心状态，每个位置在提交更改之前都会经过验证。 对于 t=2，循环以 2 为步长前进，确保正确的算术级数处理。 

一个常见的实现陷阱是忘记 t=2 的边界条件，其中最后一个元素不得超过 m； 检查`last > m`尽早避免不必要的扫描。 

## 工作示例

 ### 示例 1

 输入：```
3 7
3 2
2 2
2 2
```我们按顺序处理每场比赛。 假设我们首先放置 (k=2,t=2)。 我们扫描 x=1：天 {1,3} 是空闲的，因此我们分配开始 1 并标记第 1 天和第 3 天。 

接下来再次 (k=2,t=2)：x=1 失败，x=2 使用 {2,4}，因此我们分配起始值 2 并标记 2,4。 

最后 (k=3,t=2)：x=1 需要 {1,3,5}，但使用了 1 和 3，因此我们尝试 x=2 给出 {2,4,6}，也被阻止。 接下来 x=3 给出 {3,5,7}，但使用了 3。 x=4 给出 {4,6,8}，由于 m 无效。 所以我们需要不同的排序； 有效的重排从 2,5,1 开始。 

此跟踪显示了为什么排序和早期放置很重要：如果没有以合适的顺序考虑序列，则局部贪婪尝试可能会失败。 

### 示例 2

 输入：```
2 5
2 1
3 1
```对于长度为 2 的 t=1 区间，我们将其放置在占据 [1,2] 的 x=1 处。 下一个长度为 3 的区间只能从 x=3 开始，占据 [3,4,5]。 两者很契合，没有冲突。 这表明连续的段自然地从左到右打包，而无需回溯。

 ## 边缘情况

 一个严格的 all-t=2 实例，其中 k 相对于 m 较大，强调边界检查`x + 2(k-1) ≤ m`。 如果没有这个，算法将尝试无效的展示位置并错误地标记范围之外的日期。 

总长度恰好为 m 的密集 all-t=1 实例强制完美打包。 间隔循环中的任何差一，特别是使用`range(x, x+k-1)`而不是`x+k`，产生无声的重叠和无效的计划。 

早期 t=1 放置会阻止 t=2 的所有奇偶校验选项的混合情况说明了为什么贪婪排序很重要：即使不同的排序成功，过早放置间隔也会消除每个可行的算术级数开始。
