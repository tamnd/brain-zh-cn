 ## 解决方案
 ## 问题理解

 我们得到了几个测试用例。 每个测试用例描述一组医生，其中每个医生仅在固定的整数时间间隔内可用。 去看医生只需要一分钟，一旦我们在某个选定的时间开始这个过程，我们就必须连续拜访所有的医生，没有任何空闲时间。 

正式地，我们选择开始分钟$x$以及医生的命令。 如果医生被安排到位$i$的顺序，那么它必须在正确的时间被访问$x + i - 1$，并且这个时间必须位于该医生的可用时间间隔内。 任务是确定这样的开始时间和顺序是否存在，如果存在，则输出任何有效的构造。 

约束结构很重要。 所有测试用例中的医生总数最多为$10^5$，这排除了任何每次测试三次或二次的方法。 甚至$O(n \log n)$每个测试是可以接受的，但是任何尝试直接搜索排列或开始时间的操作都会失败。 

一个微妙的困难来自于排序和开始时间之间的耦合。 医生的可行性取决于它出现在排列中的位置，但有效位置也取决于开始时间，而开始时间是未知的。 这会在排序和对齐之间创建循环依赖关系。 

一些边缘案例说明了典型的陷阱。 如果只有一名医生，答案始终是那位拥有任何医生资格的医生$x \in [L_1, R_1]$。 例如，如果间隔非常紧密且不重叠$[1,1]$和$[3,3]$，答案是不可能的，因为我们需要连续放置它们。 当间隔重叠但不允许一致移动时，会出现另一种失败情况，例如$[1,2], [2,3], [3,4]$，其中贪婪排序似乎似乎合理，但仍然取决于仔细选择的起始对齐。 

## 方法

 一个蛮力的想法是尝试每种医生的排列和每种可能的开始时间。 对于固定排列，我们计算有效范围$x$满足所有约束条件。 对于一个有岗位的医生来说$i$，我们需要$$L_{p_i} \le x + i - 1 \le R_{p_i}$$这意味着$$L_{p_i} - (i - 1) \le x \le R_{p_i} - (i - 1).$$对于固定排列，$x$必须位于所有这些区间的交集处。 这很容易检查每个排列的线性时间。 

然而，有$n!$排列，所以即使对于$n = 10$，这已经是不可能的了。 核心的低效率在于我们将排序视为独立于可行性，而实际上排序应该由区间结构指导。 

关键的观察结果是每个医生都会为开始时间贡献一个变化的间隔$x$，并且可行性简化为找到一个排序，使得这些移位的间隔具有非空交集。 该结构暗示了一种贪婪的构造：而不是固定排列然后计算$x$，我们应该构建排列，同时保持有效范围$x$。 

我们坚持这样的想法：选择第一个之后$k$医生说，还有一个可行的时间间隔$x$。 添加该位置的下一位医生时$k$，我们将当前可行范围与该医生的移动间隔相交。 为了最大限度地提高灵活性，我们应该始终选择当前位置上最容易满足间隔约束的医生，这自然会导致根据候选者的最新可能贡献对候选者进行排序$x$。 

这将问题转化为一个具有动态缩小可行区间的贪婪调度过程。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n! \cdot n)$|$O(n)$| 太慢了 |
 | 最佳 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们根据开始时间重写每个医生的约束$x$。 如果医生被安排在某个位置$i$， 然后：$$x \in [L_i - i, R_i - i]$$（将索引移动到从零开始的位置之后）。 

问题变成：为每个医生分配一个不同的职位$0$到$n-1$，并确保所有相应的区间$x$相交。 

我们从左到右构建排列，同时保持可能值的交集$x$。 

1. 对于每个位置$i$，我们考虑所有未使用的医生并计算间隔$[L_j - i, R_j - i]$。 

该间隔代表所有有效的开始时间，如果医生$j$被放置在位置$i$。 
2. 我们维持当前的可行区间$x$， 最初$(-\infty, +\infty)$。 

选择医生后，我们将其与该医生的轮班间隔相交。 
3. 在每一步中，我们必须选择一个医生，使得更新后的交集保持非空。 

在所有有效的选择中，我们选择间隔时间允许最大灵活性的医生。 具体来说，我们根据医生的情况对医生进行分类$R_j$，这对应于尽可能延迟限制。 
4. 我们对一组候选者使用贪心选择。 在位置$i$，我们考虑所有未使用的医生，并选择一位通过确保以下条件来保持可行性的医生：$$\max(L_j - i, current\_L) \le \min(R_j - i, current\_R)$$在可行的候选者中，我们优先考虑最小的候选者$R_j$，因为它受到的限制最大，应该放在更早的位置。 
5. 我们更新当前间隔并将所选医生标记为已使用。 

当所有位置都被填满后，我们输出任何有效的开始时间$x$从最终的交集和构造的排列。 

### 为什么它有效

 该算法保持一个不变量：处理后位置$i$, 至少存在一个有效的开始时间$x$与迄今为止所有指定的医生一致。 每个贪婪的选择都确保我们不会放弃所有可行的解决方案，因为我们总是选择一个保持交集非空的医生，并首先优先考虑更严格的约束。 这可以防止未来的职位由于过度限制性的选择被延迟而变得不可行。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        L = list(map(int, input().split()))
        R = list(map(int, input().split()))

        used = [False] * n
        perm = []

        cur_L = -INF
        cur_R = INF

        # pre-pack indices
        idx = list(range(n))

        for pos in range(n):
            best = -1
            best_key = None

            for i in range(n):
                if used[i]:
                    continue
                nl = max(cur_L, L[i] - pos)
                nr = min(cur_R, R[i] - pos)
                if nl <= nr:
                    # heuristic: choose tighter R first
                    key = R[i]
                    if best == -1 or key < best_key:
                        best = i
                        best_key = key

            if best == -1:
                perm = None
                break

            perm.append(best + 1)
            used[best] = True

            cur_L = max(cur_L, L[best] - pos)
            cur_R = min(cur_R, R[best] - pos)

        if perm is None:
            print(-1)
            continue

        x = cur_L
        print(x)
        print(*perm)

def main():
    solve()

if __name__ == "__main__":
    main()
```实现直接遵循贪心构造。 关键细节是，在每个位置，我们使用当前有效的交集重新计算可行性$x$。 更新步骤`cur_L = max(cur_L, L[best] - pos)`和`cur_R = min(cur_R, R[best] - pos)`是相交移位约束的精确转换。 

一个微妙的实施风险是忘记转变取决于当前位置，而不是医生索引。 另一个问题是未能确保在做出选择之前检查交集，这将默默地产生无效的排列。

 ## 边缘情况

 一个关键的边缘情况是所有医生的时间间隔都相同。 例如，所有$[1,1]$。 算法强制$x$恰好为 1 并且任何排列都是有效的，因为只有当位置偏移完全匹配约束时，每个位置移位才保留可行性。 相交逻辑正确地折叠到一个点并且永远不会变得不一致。 

当间隔足够宽以允许多个放置但仅在一个全局排序中时，会出现另一种边缘情况。 在这种情况下，首先通过收紧约束进行贪婪选择，确保尽早安排限制性医生，防止以后出现不可行的情况。
