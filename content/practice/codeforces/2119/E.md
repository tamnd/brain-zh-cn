 ## 解决方案
 ## 问题理解

 我们有两个序列，`a`长度`n-1`和`b`长度`n`。 目标是增加元素`b`使用最少的增量，以便对于每个相邻的对`(b_i, b_{i+1})`，它们的按位与等于`a_i`。 每次增量正好增加一个元素 1，并且我们不能减少任何元素。 输出是最小增量数或`-1`如果不可能满足所有条件。 

限制很严格。 和`n`最多`10^5`和总和`n`超过所有测试用例`2*10^5`，任何比线性慢的解`n`会太慢。 尝试所有增量序列的简单暴力方法是不可行的，因为操作数量可能会快速增长 - 对于大型数据库`b_i`和`a_i`，每个元素可能需要最多`2^29`增量。 这立即排除了任何迭代单个增量的解决方案。 

边缘情况很微妙。 如果`a_i`包含为零的位，我们必须确保至少有一个相应的位`b_i`或者`b_{i+1}`可以在不违反之前的 AND 约束的情况下增加。 粗心的做法可能会贪婪地增加`b_i`匹配`a_i`而不考虑它如何影响`b_{i-1} & b_i`。 例如，考虑`a = [1, 0]`和`b = [0, 0, 0]`。 只需增加第一个元素即可满足`b_1 & b_2 = 1`可能会让人无法满足`b_2 & b_3 = 0`。 

另一个极端情况出现时`b`已经满足一些 AND 约束。 盲目增加可能会过度并增加不必要的操作数量。 

## 方法

 蛮力方法会尝试所有增量序列`b`直到所有`b_i & b_{i+1} = a_i`抓住。 原则上它是正确的，但速度却慢得离谱。 对于每对`(b_i, b_{i+1})`，如果我们需要匹配特定的`a_i`，我们可以尝试所有增量组合`b_i`和`b_{i+1}`。 即使只有 30 位，可能的增量数量也是指数级的。 

最佳解决方案的关键见解是 AND 运算相对于增量是单调的。 如果某个位为 0`a_i`，那么至少其中之一`b_i`或者`b_{i+1}`该位中必须有 0。 如果一个位是 1`a_i`， 两个都`b_i`和`b_{i+1}`该位中必须有 1。 这意味着我们可以独立地一点一点地解决问题。 我们可以表示每个的最小值`b_i`需要满足所有约束作为下限。 那么，最小增量数就是该下限与原始值之间的差值之和`b_i`。 该解是线性的`n`并按位最多处理 30 位，给出 O(30 * n) 时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 按位贪婪 / DP | O(n * 30) | O(n) | 已接受 |

 ## 算法演练

 1. 对于从 0 到 29 的每个位位置，确定该位是否在`a_i`是否设置。 对于每个`a_i`，如果某个位为 1，则两者`b_i`和`b_{i+1}`最终必须设置该位。 如果某位为 0，则至少有一个`b_i`或者`b_{i+1}`可以取消设置该位。 
2. 初始化`min_b[i]`到`b[i]`对于每个`i`。 这表示我们必须在索引处达到的最小值`i`增量后。 
3. 迭代`a`从左到右。 对于每个`i`和每一位，如果`a_i`该位有一个 1，确保`min_b[i]`和`min_b[i+1]`两者都通过可能将它们增加到设置该位的下一个值来设置该位。 如果任何调整需要减少`b_i`，这是不可能的，我们返回`-1`。 
4. 处理完所有对的所有位后，最少的操作次数是所有操作的总和`i`的`min_b[i] - b[i]`。 
5. 输出测试用例的总和。 

该算法之所以有效，是因为 AND 约束是按位可分离的。 对于每一位，要求只是所涉及元素的下限。 增加元素只会影响未来的操作（如果它们在 AND 对中重叠），但通过沿序列传播最低要求，我们保证了可行性。 该算法永远不会高估增量，因为每个位都设置为最小的必要级别。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        min_b = b[:]
        possible = True

        for bit in range(30):
            mask = 1 << bit
            for i in range(n - 1):
                if a[i] & mask:
                    if not (min_b[i] & mask):
                        min_b[i] |= mask
                    if not (min_b[i + 1] & mask):
                        min_b[i + 1] |= mask
                else:
                    if (min_b[i] & mask) and (min_b[i + 1] & mask):
                        possible = False
                        break
            if not possible:
                break

        if not possible:
            print(-1)
        else:
            ops = sum(min_b[i] - b[i] for i in range(n))
            print(ops)

solve()
```代码首先读取测试用例的数量。 对于每种情况，它都会复制`b`进入`min_b`，它将跟踪最小调整值。 对于从 0 到 29 的每一位，我们将所需的位约束传播到相邻元素。 如果有一个零位`a[i]`两者都有冲突`b_i`和`b_{i+1}`既然已经设定了，这个任务是不可能的。 最后，增量之和给出最少的操作。

 | 0 | 1 | 1 | a[0]=1 的位 0，已经满足 |

 返回-1，显示不可能的情况。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n * 30) | 对于 30 位中的每一位，我们迭代 n-1 对来传播约束 |
 | 空间| O(n) | 我们将 b 的副本存储在 min_b | 中

 和`n`每个测试用例最多 10^5、30 * n = 3_10^6 次操作。 由于所有测试用例的总 n ≤ 2_10^5，这很容易在 2 秒内完成。
