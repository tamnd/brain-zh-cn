[CF 57B - 火星建筑](https://codeforces.com/problemset/problem/57/B)

 **求解时间：** 1m 37s

 ## 解决方案
 ## 问题理解

 每个结构都描述了放置在一维单元线上的楼梯。 楼梯从牢房开始`l`，以单元格结束`r`，并以算术级数相加高度。 如果起始高度是`x`，则添加的石子为：`x`在`l`

`x + 1`在`l + 1`

`x + 2`在`l + 2`依此类推，直到`x + (r - l)`在`r`。 

几个楼梯可能会重叠，并且它们的贡献会累积。 

我们没有被要求重建整条道路。 相反，仅`k`特定的细胞很重要。 在应用所有楼梯后，我们需要这些查询单元中存在的石头总数。 

输入给出：

 - 细胞数量，
 - 楼梯结构清单，
 - 一组有趣的单元格，其最终的石头计数必须相加。 

最大值约为`10^5`，这立即排除了任何二次方。 更新每个楼梯的每个受影响单元的直接模拟可能会执行`10^10`最坏情况下的操作，远远超出2秒的限制。 

有趣的细节是`k ≤ 100`。 仅查询少量单元格。 这完全改变了方向。 我们可以只处理查询的位置，而不是更新每个楼梯接触的每个单元。 

一些边缘情况很容易处理不当。 

假设楼梯在查询的单元格之前开始，在其之后结束。```
5 1 1
1 5 3
4
```查询的单元格为`4`。 楼梯有助于：`3 4 5 6 7`细胞`4`收到`6`， 不是`3`而不是`7`。 仅存储起始值的粗心实现将无法考虑与楼梯起点的偏移。 

当查询的单元格位于楼梯间隔之外时，会出现另一种微妙的情况。```
5 1 2
2 4 1
1 5
```楼梯只影响细胞`2,3,4`。 正确答案是`0`。 间隔检查中的相差一错误通常会错误地包括边界单元。 

重叠的楼梯也很重要。```
5 2 1
1 3 1
2 5 2
3
```第一个楼梯有贡献`3`到细胞`3`。 

第二个楼梯有贡献`3`到细胞`3`。 

最终值为`6`。 

天真的覆盖而不是累积会给出错误的结果。 

最后，答案可能会超出32位整数范围。 尽管每个楼梯最多从`1000`, 可以有`10^5`楼梯。 实现必须使用 64 位算术。 

## 方法

 最直接的解决方案是明确地构建整条道路。 

对于每一个楼梯`(l, r, x)`，我们迭代所有受影响的单元格并添加适当的算术级数值：```
cell l     += x
cell l + 1 += x + 1
cell l + 2 += x + 2
...
```处理完所有楼梯后，我们对查询的单元格进行求和。 

这在逻辑上是有效的，因为每个楼梯贡献都恰好应用到每个被覆盖的位置一次。 问题是成本。 一个楼梯可以覆盖`10^5`细胞，并且可能有`10^5`楼梯。 这导致大约`10^10`最坏情况下的更新。 

关键的观察是我们永远不需要所有单元格的值。 最多只`100`职位很重要。 

我们可以迭代所有查询的位置并检查楼梯是否影响它们，而不是迭代楼梯内的所有单元格。 

假设我们处理一个查询的单元格`p`。 

一个楼梯`(l, r, x)`有助于`p`仅当：```
l ≤ p ≤ r
```如果楼梯覆盖`p`，那么增加的值为：```
x + (p - l)
```因为向右每一步都会使高度增加一。 

现在总工作变成：```
m × k
```自从`m ≤ 100000`和`k ≤ 100`, 最大值仅为`10^7`检查，这在 Python 中是完全可以接受的。 

蛮力之所以有效，是因为它确实模拟了每一个添加的石头。 优化的解决方案之所以有效，是因为查询集很小，因此仅检查相关位置比构建整条道路便宜得多。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(纳米) | O(n) | 太慢了 |
 | 最佳| O(mk) | O(k) | 已接受 |

 ## 算法演练

 1. 读取所有查询到的职位并将其存储在列表中。 

由于只有这些位置很重要，因此不需要跟踪其他单元格。 
2. 创建数组`ans`长度`k`。`ans[i]`将存储在`i-th`被询问的位置。 
3、处理每个楼梯`(l, r, x)`逐个。 

每个楼梯都是独立的，因此我们可以立即将其贡献添加到所有相关的查询单元格中。 
4. 对于每个查询的位置`p`：

 检查是否`l ≤ p ≤ r`。 

如果为 false，则该楼梯对`p`。 
5.如果楼梯覆盖`p`， 添加：```
x + (p - l)
```到相应的答案条目。 

期限`(p - l)`表示所查询的单元格距离楼梯起点向右有多少步。 
6. 处理完所有楼梯后，将所有楼梯的条目求和`ans`。 

This gives the total number of stones across all queried cells.

 ### 为什么它有效

 对于每个楼梯和每个查询的位置，算法都会考虑两种可能性中的一种。 

If the queried cell lies outside the staircase interval, the staircase contributes nothing.

 如果查询的单元格位于间隔内，则阶梯将准确贡献与其距起始单元格的距离相对应的算术级数值。 

由于每个楼梯的贡献都是独立添加的并且累积是线性的，因此每个查询单元格的最终存储值等于该单元格中石头的真实总数。 Summing those values produces the required answer.

 ## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    roads = [tuple(map(int, input().split())) for _ in range(m)]
    queries = list(map(int, input().split()))

    ans = [0] * k

    for l, r, x in roads:
        for i in range(k):
            p = queries[i]

            if l <= p <= r:
                ans[i] += x + (p - l)

    print(sum(ans))

solve()
```该解决方案仅保留查询的位置，而不是构建大小的数组`n`。 

外循环遍历楼梯。 内循环检查所有查询的单元格。 自从`k`至多是`100`，即使当`m`达到`100000`。 

表达式：```
x + (p - l)
```是解决方案的核心。 如果楼梯开始于`l`与高度`x`，然后向右移动一个单元格会将添加的棋子增加一。 查询位置`p`正是`p - l`离起点还差一步。 

间隔检查：```
if l <= p <= r:
```很关键。 忘记任一边界都会在边缘产生不正确的贡献。 

最终答案是所有查询单元格值的总和，而不是各个值本身。 该问题要求一个总和。 

Python 整数自动处理大值，因此溢出不是问题。

 ## 边缘情况

 考虑楼梯内的一个查询单元，但距离起点很远。```
5 1 1
1 5 3
4
```楼梯增加了：```
3 4 5 6 7
```处理查询时`4`，算法计算：```
3 + (4 - 1) = 6
```与真实贡献相符。 这证实了偏移公式是正确的。 

现在考虑完全在所有楼梯之外的查询单元。```
5 1 2
2 4 1
1 5
```供查询`1`，条件`2 ≤ 1 ≤ 4`失败。 

供查询`5`，条件`2 ≤ 5 ≤ 4`也失败了。 

没有添加任何贡献，因此两个查询单元格都保持为零，最终答案是`0`。 

重叠的楼梯是另一个常见的虫子来源。```
5 2 1
1 3 1
2 5 2
3
```第一个楼梯贡献：```
1 + (3 - 1) = 3
```第二个贡献：```
2 + (3 - 2) = 3
```该算法将两个值添加到同一个累加器中：```
3 + 3 = 6
```与预期结果相符。 

最后，考虑区间边界。```
5 1 2
2 4 1
2 4
```查询时`2`，贡献为：```
1 + (2 - 2) = 1
```查询时`4`，贡献为：```
1 + (4 - 2) = 3
```最终的答案是`4`。 

这确认了两端都包含间隔检查。
