 ## 解决方案
 ## 问题理解

 我们有一个机器人站在无限二维网格的原点，我们需要引导它到达具有坐标的目标单元$(x, y)$。 机器人可以向北、向东、向南、向西移动或停留在原地，但不能连续重复相同的命令。 输入为我们提供了多个测试用例，每个测试用例指定一个目的地$(x, y)$。 对于每个目的地，我们必须确定机器人到达的最小移动次数$(0, 0)$到$(x, y)$同时遵守非连续命令限制。 

限制是适度的。 拥有多达 100 个测试用例和多达 100 个坐标$10^4$，我们需要一种算法来计算每个测试用例的线性时间结果。 任何尝试模拟所有可能的移动序列的方法都会太慢，因为潜在序列的数量呈指数增长$x + y$。 

当以下任一情况出现边缘情况$x$或者$y$为零，因为交替命令需要仔细处理。 例如，从$(0, 0)$到$(2, 0)$，一个幼稚的策略可能会建议向东移动两次，但机器人做不到`E E`连续，因此最小序列实际上在两者之间使用“stay”命令：`E 0 E`。 类似地，当两个坐标都为零时，机器人已经到达目的地并且需要零命令。 

## 方法

 暴力方法将尝试生成尊重“不重复”规则并达到的所有移动序列$(x, y)$。 这种方法原则上是正确的，但它是不可行的，因为对于大坐标，序列的数量呈指数增长，大约为$2^{x+y}$在最坏的情况下。 

关键的见解是，只有当我们朝同一方向连续移动时，限制才有意义。 为了避免重复相同的命令，我们可以在需要移动的两个方向之间交替：南北和东西。 实际上，最小序列长度仅取决于较大的$x$和$y$。 如果两个坐标相等，我们可以交替移动而无需额外的“停留”命令，从而准确地产生$x + y$移动。 如果坐标不相等，则在沿较小维度交替后，机器人必须为较小维度之外的较大维度中的每个剩余步骤插入一个额外的移动。 这导致公式`2 * max(x, y) - 1`如果`x != y`， 和`x + y`如果`x == y`。 

下表总结了这些方法：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^(x+y)) | O(2^(x+y)) | O(x+y) | 太慢了|
 | 最佳 | 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量$t$。 
2. 对于每个测试用例，读取目标坐标$x$和$y$。 
3. 如果两者都$x$和$y$为零，输出 0 并继续，因为不需要移动。 
4.确定较小的坐标$a = \min(x, y)$和更大的坐标$b = \max(x, y)$。 
5.如果$x$和$y$相等，输出$x + y$，因为我们可以完美地交替移动，而不需要任何额外的步骤。 
6. 如果$x$和$y$不相等，输出`2 * b - 1`。 这说明了向上到较小坐标的交替移动，以及完成较大坐标中剩余移动而不重复上一个命令所需的额外步骤。 
7. 对所有测试用例重复此操作。 

不变量是机器人总是交替方向，直到耗尽一个坐标。 较大坐标中的任何剩余移动都需要交错停留或相反方向移动，为每个剩余步骤添加一个额外命令。 此逻辑保证了最小数量的命令，同时遵守“无连续重复”规则。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    x, y = map(int, input().split())
    if x == 0 and y == 0:
        print(0)
        continue
    a, b = min(x, y), max(x, y)
    if x == y:
        print(x + y)
    else:
        print(2 * b - 1)
```该代码首先处理以下简单情况`(0, 0)`以避免不必要的计算。 然后，它计算最小和最大坐标，以确定路径是否可以完美交替。 如果坐标相等，则总和给出最小移动。 否则，我们应用导出公式`2 * max(x, y) - 1`。

 ## 边缘情况

 当机器人必须仅沿一个轴移动时，交替规则会强制在重复移动之间插入停留命令。 用于输入`(2, 0)`,`a = 0`和`b = 2`。 公式给出`2 * 2 - 1 = 3`，对应于序列`E 0 E`。 为了`(0, 0)`，输出为 0，因为不需要命令。 对于大的相等坐标，例如`(10000, 10000)`，沿两个轴交替移动恰好产生`x + y = 20000`，显示算法正确缩放。 每个边缘情况都遵循机器人在使用最少步数时不会连续重复命令的不变性。
