 ## 问题理解

 我们需要选择观看系列剧的最早开始时刻。 唯一给出的信息是剧集的持续时间（以分钟为单位）。 有效开始时间是开头显示的四位数字和结尾显示的四位数字均不相同的时钟时间。 

时钟使用通常的 24 小时格式，因此时间由两位数表示小时和两位数表示分钟。 如果剧集超过午夜，则结束时间从第二天继续，并显示为正常时钟时间。 我们只需要显示的结束时间，而不是过去的天数。 

持续时间可以长达一整天。 这立即限制了有用的搜索空间：一天内只有 1440 分钟可能的起始时间。 检查每个可能的开始时间并验证数字的解决方案仅执行几千次操作，这很容易在时间限制内。 更复杂的算法是不必要的，因为整个状态空间很小。 

主要的边缘情况来自于错误地处理时钟表示。 一个常见的错误是忘记前导零。 例如，时间 6:39 必须被视为 06:39，因为第一个数字是显示的一部分。 用于输入`1`, 开始时间`00:00`无法工作，因为显示的四个数字已经重复。 

另一个错误是错误地处理午夜。 用于输入`60`，开始于`23:30`结束于`00:30`。 比较必须使用显示的结束时间`00:30`， 不是`24:30`。 

第三种边缘情况是一整天的持续时间。 用于输入`1440`，每个开始和结束显示相同的时钟时间，因此八位数字不能全部不同。 正确的输出是`PASS`。 

## 方法

 最简单的方法是模拟每一个可能的开始时间。 对于 1440 个时钟位置中的每一个，我们在添加剧集持续时间后计算结束位置。 然后我们将两次都转换为四位数字字符串，并检查组合后的八个字符是否包含重复。 如果找到有效时间，则第一个遇到的时间自动为最早的时间。 

这种蛮力方法已经足够快了，因为候选者的最大数量是固定的。 即使在最坏的情况下，我们也会检查 1440 个开头，并且每次检查仅检查八位数字。 总工作量约为 11520 次数字比较，这是很小的。 

不需要更复杂的优化。 这个问题看起来可能需要时间搜索，但完整的时间线只有24小时。 有用的观察结果是，对答案空间的约束是如此之小，以至于直接枚举是最干净且最不容易出错的解决方案。

 ## 算法演练

 1. 尝试每一个可能的开始分钟`00:00`通过`23:59`。 由于当天仅包含 1440 个可能的位置，因此检查所有位置即可给出准确的最早答案。 
2. 将起始分钟转换为小时和分钟。 单独保留四位数字，包括前导零。 
3. 将剧集持续时间添加到开始分钟。 将结果对 1440 求模即可得出剧集结束后显示的时钟时间。 
4. 将结束分钟转换为相同的四位数字表示形式。 
5. 将四个起始数字和四个结束数字组合起来。 如果每个数字都恰好出现一次，则该开始时间满足要求。 
6. 打印找到的第一个有效开始时间。 如果 1440 种可能性全部失败，则打印`PASS`。 

为什么有效：该算法按时间顺序检查每个可能的开始时间。 有效的答案必须是那些被检查的时刻之一。 由于遇到的第一个有效时刻是最小的，因此算法无法跳过较早的解。 数字测试完全符合显示的八个数字必须不同的条件，因此每个打印的答案都是有效的。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    k = int(input())

    for start in range(1440):
        end = (start + k) % 1440

        sh = start // 60
        sm = start % 60
        eh = end // 60
        em = end % 60

        digits = [
            sh // 10,
            sh % 10,
            sm // 10,
            sm % 10,
            eh // 10,
            eh % 10,
            em // 10,
            em % 10,
        ]

        if len(set(digits)) == 8:
            print(f"{sh:02d}:{sm:02d}")
            return

    print("PASS")

if __name__ == "__main__":
    solve()
```循环结束`range(1440)`代表一天中所有可能的起点。 由于顺序是从一天的开始到结束，所以第一个成功的检查就是所需的答案。 

由于时钟在午夜后绕行，因此结束时间以模 1440 计算。 如果没有此操作，诸如 1500 分钟之类的值将产生无效的时钟表示。 

这些数字存储为整数，而不是手动构建字符串。 这`set`大小检查之所以有效，是因为八个唯一的数字必须生成一个恰好包含八个元素的集合。 格式化表达式`:02d`仅在打印时使用，因为小时和分钟必须始终包含两位数字。

 ## 边缘情况

 用于输入`1440`，每个候选开始时间都在完全相同的显示时钟时间结束。 例如，`12:34`变成`12:34`。 数字列表必然包含重复项，因此算法会拒绝每个候选者并打印`PASS`。 

用于输入`1`, 最早的候选者`00:00`结束于`00:01`。 这些数字并不唯一，因为出现了几个零。 该算法继续进行，直到到达第一对，其中显示的八个数字全部不同。 这可以防止忽略重复零的错误解决方案。 

用于输入`60`，接近一天结束时的候选人可以跨越午夜。 开始于`23:30`产生`00:30`，并且该算法可以正确处理此问题，因为在提取数字之前结束时间会以 1440 为模减少。 

无论持续多久，答案都可能不存在。 决赛`PASS`仅在检查了每个可能的起始分钟后才达到输出，因此不会错过任何有效时间。
