 ## 解决方案
 ## 问题理解

 输入描述了一个犯罪网络。 每个罪犯都是无向图的一个顶点，每个记录的连接都是两个顶点之间的一条边。 犯罪群体是犯罪分子的相互联系的群体，但单个孤立的犯罪分子不能算作一个群体。 任务是确定图的多少个连通分量包含至少两个顶点。 

第一行给出了犯罪分子的数量和记录的连接数量。 以下几对描述了哪些犯罪分子有直接联系。 连接可以形成链条，因此两个犯罪分子属于同一社区，即使他们之间没有直接边缘，只要有一条通过其他犯罪分子的路径。 输出是此类重要连接组件的数量。 

罪犯数量最多为100个，连接数可以为罪犯数量的平方。 有了这些限制，即使是简单的图遍历方法也很容易足够快。 时间复杂度约为 O(N + M) 的解决方案就足够了。 重复搜索所有犯罪分子之间的所有路径的更昂贵的方法是不必要的，并且会执行比问题结构所需的更多的工作。 

有几种情况需要小心。 即使存在顶点，不包含真实社区的图也应该产生零。 

例如：```
3 0
```答案是：```
0
```将每个顶点都算作一个组件的粗心实现会错误地返回 3。 

一对有联系的犯罪分子必须算作一个社区。 

例子：```
2 1
0 1
```答案是：```
1
```仅查找具有许多边的顶点的实现可能会错过这一点，因为每个罪犯只有一个连接。 

自我联系并不会将孤立的罪犯变成一个社区。 

例子：```
3 1
1 1
```答案是：```
0
```顶点有一个环，但连接的组件仍然只包含一名罪犯。 对包含边缘的每个组件进行计数的解决方案会产生错误的结果。 

## 方法

 直接暴力的想法是从每一个罪犯开始，搜索所有可以到达的罪犯。 找到可达集后，我们可以检查它的大小是否大于 1，并将其算作一个社区。 为了避免对同一社区进行多次计数，我们需要跟踪哪些犯罪分子已经得到处理。 

如果没有这种优化，就会重复探索相同的组件。 在最坏的情况下，包含 100 名犯罪分子的密集图可能有大约 10,000 个连接。 从每个顶点运行完整遍历将执行大约 O(N(N + M)) 操作，这里大约是一百万次操作。 它仍然会通过这些约束，但它忽略了任务的更简单的结构。 

关键的观察结果是，社区恰好是无向图的连通组件。 我们不需要寻找特定犯罪分子之间的路径。 我们只需要发现每个连接区域一次并检查其大小。 

诸如深度优先搜索或广度优先搜索之类的图遍历自然可以做到这一点。 从未访问过的罪犯开始，遍历访问同一组件中的每个人。 遍历完成后，我们就知道了组件的大小。 如果该大小至少为 2，则贡献一颗星。 

蛮力之所以有效，是因为可以通过图遍历来发现可达性，但它在概念上失败了，因为它重复了相同的工作。 每个罪犯都属于一个连通组件的观察结果让我们只处理每个顶点和边一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N(N + M)) | O(N(N + M)) | O(N) | 在这里可以工作，但没有必要 |
 | 最佳| O(N + M) | O(N + M) | 已接受 |

 ## 算法演练

 1. 为图构建邻接表。 对于两个不同犯罪分子之间的每个连接，将每个端点存储在对方的列表中，因为该图是无向的。 自循环可以被存储或忽略，因为大小为 1 的组件永远不会对答案做出贡献。 
2. 创建一个数组，记录每个罪犯是否已经被访问过。 最初，每个罪犯都未被访问过，因为没有探索过任何连接的组件。 
3. 遍历所有罪犯。 当发现一个未访问过的罪犯时，从它开始 DFS 并计算到达了多少个顶点。 遍历标记了这个连接组件中的每个罪犯，因此以后的迭代将跳过同一社区。 
4. DFS 完成后，检查发现的组件的大小。 如果其中至少包含两名罪犯，则将答案增加一名。 单个被访问的顶点只是一个孤立的犯罪分子，而不是一个社区。 
5. 打印最终计数的成分数。 

为什么它有效：

 算法过程中的不变性是每次完成的 DFS 遍历都恰好代表一个连通分量。 DFS 只沿着现有的边移动，因此它不能离开该组件。 同时，通过路径可到达的每个顶点最终都会被访问，因此不会遗漏组件的任何成员。 由于每个顶点仅在以前没有见过时才启动一个 DFS，因此每个连接的组件都被精确计数一次。 最终的大小检查删除了单顶点组件，符合犯罪社区的定义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n)]

    for _ in range(m):
        x, y = map(int, input().split())
        if x != y:
            graph[x].append(y)
            graph[y].append(x)

    visited = [False] * n
    answer = 0

    for start in range(n):
        if visited[start]:
            continue

        stack = [start]
        visited[start] = True
        size = 0

        while stack:
            v = stack.pop()
            size += 1

            for to in graph[v]:
                if not visited[to]:
                    visited[to] = True
                    stack.append(to)

        if size > 1:
            answer += 1

    print(answer)

if __name__ == "__main__":
    solve()
```该图被存储为邻接表，因为遍历只需要知道哪些罪犯是直接相连的。 存储完整的邻接矩阵也可以满足约束条件，但它会使用更多的内存，并且会使解决方案与图遍历思想的直接联系减少。 

迭代DFS使用堆栈而不是递归。 Python 递归深度可能会成为较大图形任务中长链上的问题，因此显式堆栈避免了该限制。 

变量`size`计算当前连接组件中的顶点数。 它仅在遍历结束后进行检查，因为算法必须知道整个组件的大小才能决定它是否代表一个社区。 

构建图表时忽略自循环是安全的。 自循环永远不会在组件中创建另一个顶点，唯一重要的问题是组件大小是否超过 1。

 ## 边缘情况

 仅包含孤立罪犯的输入：```
3 0
```从每个顶点开始 DFS，但每次遍历都只访问一个顶点。 大小检查拒绝所有三个分量，将答案保留为 0。该算法会处理此问题，因为连接性和社区大小是分开检查的。 

连接对：```
2 1
0 1
```导致第一个 DFS 访问两个顶点。 组件大小变为 2，因此答案增加到 1。该算法不要求组件有很多边，只需要多个顶点。 

自循环：```
3 1
1 1
```不会创建有效的社区。 图表示忽略了循环，并且来自顶点 1 的 DFS 的大小仍然为 1。答案仍然为 0，因为单个犯罪分子无法形成社区。 

具有多个断开连接的组的图：```
6 3
0 1
1 2
4 5
```被处理为三个组件。 第一个尺寸为 3，贡献一颗星，第二个是孤立的，不贡献任何内容，第三个尺寸为 2，并贡献一颗星。 最终答案是 2。这证实了遍历独立地计算分量而不是计算顶点或边。
