 ## 问题理解

 输入是一个写为二进制字符串的正整数。 任务是找到最大的指数`b`这样所表示的数字可以除以`2^b`无余。 

在二进制中，除以2的幂有非常直接的含义。 删除二分之一会将二进制表示向右移动一位。 二进制数可以被`2`,`4`,`8`，依此类推，当它末尾有足够的零位时。 答案是二进制字符串末尾连续零的数量。 

输入中的位数可以达到 1000。这足够小，我们可以直接检查整个字符串，但这也意味着我们不应该依赖将其转换为普通整数类型。 1000 位数字远远超出了大多数语言内置的固定宽度整数的范围。 线性扫描很容易足够快，因为它只执行大约一千个字符检查。 

主要的边缘情况来自最后一个的位置`1`在二进制表示中。 如果数字已经是奇数，则不存在二的因数。 例如，输入`1011`代表11，输出为`0`。 粗心的解决方案从错误的一侧计算零可能会错误地返回正值。 

另一个边界情况是 2 本身的幂。 用于输入`1000`，答案是`3`因为`1000₂ = 8 = 2^3`。 计算第一个字符之后的字符数的实现`1`在这种情况下，而不是尾随零的数量会失败。 

最小的有效数字是`1`。 它的二进制形式没有尾随零，因此正确的输出是`0`。 假设最后一个后面总是至少有一个零的代码`1`可能会访问无效位置或产生不正确的结果。 

## 方法

 一种简单的方法是在数字仍能被二整除的情况下重复将其除以二。 每次成功除法后，答案都会加一。 这在数学上是正确的，因为成功除法的次数正是原始值除以 2 的最高次方。 

问题在于，该数字以最多 1000 位的二进制字符串形式给出，因此实现重复除法需要昂贵的字符串运算或手动二进制算术。 每个除法可以触及许多数字，在最坏的情况下，像这样的数字`1000...000`包含 999 个二的因数。 模拟可以执行接近`1000 * 1000`数字运算，这是不必要的。 

关键的观察结果是，二进制除以二只是删除了最后一位。 唯一重要的是从字符串末尾读取时在最后一个零位之前出现了多少个零位。 我们可以直接检查其表示，而不是重复更改数字。 

暴力方法之所以有效，是因为每次除法都会消除二分之一，但它会失败，因为它重复了二进制表示已经公开的工作。 尾随零计数一次给出相同的信息。

 ## 算法演练

 1. 将二进制表示形式读取为字符串。 将其保留为文本可以避免整数大小的任何问题，因为输入最多可以包含 1000 位。 
2. 从最后一个字符开始，向左移动当前字符`0`。 找到的每个零都代表二的一个因数，因为每个尾随零意味着该数字可以被另一个二的幂整除。 
3.到达第一个时停止`1`。 遇到的零的个数就是最大指数`b`。 
4. 打印计数器。 

这样做的原因是每个正二进制数都有一个独特的形式，其中一些前缀以`1`并且所有剩余位均为零。 这些最后的零正是可以删除的二的因数。 一次`1`达到时，剩余的数字是奇数，因此不可能再被二除。 

## 为什么它有效

 该算法保持了这样的不变性：计数的字符恰好是二的去除因子。 以一个零结尾的二进制数可以被二整除。 如果它以两个零结尾，则它可以被四整除，依此类推。 扫描对每个这样的零进行计数，并在第一位停止，以防止再次除法。 由于奇数二进制数总是以`1`，停止点证明没有更大的2的幂可以整除原始数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    ans = 0
    i = len(s) - 1

    while i >= 0 and s[i] == '0':
        ans += 1
        i -= 1

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案将输入保留为字符串，因为将 1000 位二进制值转换为整数是不必要的，并且在许多环境中可能会超出正常的整数限制。 

变量`i`从最后一位开始，因为能被 2 的幂整除仅取决于低位。 当循环找到尾随零时，它会准确地增加答案，然后移向更高的有效位。 

循环条件检查`i >= 0`访问之前`s[i]`，防止无效索引。 对于有效的正二进制数，扫描最终将达到`1`，但边界检查也使代码安全。 

不对实际数字执行算术运算，因此不存在溢出问题，并且实现直接遵循算法中使用的二进制属性。

| 当前位置 | 当前位| 回答 |

 扫描在末尾计算三个零并在第一个零处停止`1`。 答案是`3`，意味着该数字可以被整除`2^3`但不是由`2^4`。 

这些示例显示了两种重要情况：没有 2 的因数的数字和由其尾随位直接表示的具有 2 的多个因数的数字。

 ## 边缘情况

 用于输入`1011`，算法从最后一个字符开始，看到`1`，并立即停止。 答案依然存在`0`。 这是正确的，因为表示的值是奇数并且不能被二除。 

用于输入`1000`，扫描在到达第一个零之前访问了三个零`1`。 计数器变为`3`，这与事实相符`1000₂`是`8`， 和`8`可以整除`2^3`。 

用于输入`1`，索引从唯一的字符开始。 既然是`1`，循环永远不会执行，输出是`0`。 这避免了假设尾随零的存在。 

用于输入`1000000000`，扫描对前导后的每一个零进行计数`1`。 这样的零有九个，所以答案是`9`。 该算法不会将字符串的长度与指数混淆，因为它只计算由零位组成的后缀。
