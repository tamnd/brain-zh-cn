 ## 解决方案
 # 问题理解

 HyperLoop 网络可以被视为有向图`n`站。 每个车站都有两个出站边缘：左隧道和右隧道。 重复走左隧道意味着应用一种功能，重复走右隧道意味着应用另一种功能。 

每个查询给出一个起始站`x`, 向左移动的次数`a`, 一些正确的动作`b`，以及硬币结果`c`。 如果`c = 0`，行程包括`a`向左移动，然后`b`正确的动作。 如果`c = 1`，顺序相反。 任务是在两块移动之后找到最终站。 

困难的部分是该图只有`100000`站，但移动次数可达`10^15`。 模拟移动是不可能的，因为即使一个查询也可能需要千万亿次转换。 和`500000`查询，任何接近的解决方案`O(nq)`甚至`O(q * min(a,b))`远远超出了可用时间。 我们需要对图进行预处理，以便可以在大约对数时间内回答每个查询。 

图的结构很特别。 每种隧道类型单独创建一个功能图：每个站点都恰好有一个传出左边缘和一个传出右边缘。 函数图包含有向循环，树通向它们，这正是二元提升工作良好的结构。 

一些边缘情况可能会破坏粗心的实施。 第一个是零步查询。 例如：```
n = 1
left: 1
right: 1
query: 1 0 0 0
```答案是：```
1
```始终执行至少一次跳跃的解决方案将错误地离开空间站。 

另一个棘手的情况是与大幂混合的自循环：```
n = 2
left: 1 1
right: 2 2
query: 2 1000000000000000 7 0
```答案是：```
1
```第一次左移后，车站变为`1`，并且每一次进一步向左移动都停留在那里。 基于循环检测的方法必须正确处理长度为 1 的循环。 

两个操作的顺序也很重要。 例如：```
n = 3
left: 2 3 3
right: 1 1 2
query: 1 1 1 0
```答案是：```
1
```路径是`1 -> 2`使用左侧隧道，然后`2 -> 1`使用正确的隧道。 颠倒顺序会产生不同的转换，因此将查询视为一个组合操作是不正确的。 

## 方法

 直接的解决办法就是模拟行程。 对于每个查询，从`x`，沿着所需的隧道行驶`a`次，然后沿着另一条隧道行驶`b`次。 这是正确的，因为每次移动都恰好是所选隧道定义的边缘。 然而，最坏的情况是巨大的。 一个查询可能需要`10^15 + 10^15`过渡，以及`500000`这样的查询需要大约`10^21`运营。 

关键的观察结果是两个隧道系统是独立的。 我们永远不需要在左右隧道之间交替。 每个查询仅要求左函数的一次幂和右函数的一次幂。 如果我们能回答“这个站之后去哪里”`k`向左移动？”很快，整个查询就变成了两个独立的跳转。

 二进制提升正是提供了这种操作。 对于每种隧道类型，我们存储每个车站到达后的位置`2^j`移动。 任何值高达`10^15`最多可以使用 50 个二进制位来表示，因此跳转可以分解为最多 50 个存储的转换。 

暴力破解之所以有效，是因为逐条追踪的边与过程完全匹配，但它会失败，因为所经过的边的数量太大。 观察到每种隧道类型都是一个函数图，我们可以用对数数量的预先计算的跳跃来代替长距离行走。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个查询 O(a + b) | O(1) | O(1) | 太慢了|
 | 二元提升| O(n log 10^15 + q log 10^15) | O(n log 10^15 + q log 10^15) | O(n log 10^15) | O(n log 10^15) | 已接受 |

 ## 算法演练

 1. 建造两个二元升降台，一个用于左侧隧道，一个用于右侧隧道。 第一层存储一次移动后的直接目的地。 每个下一级存储的目的地是上一级移动次数的两倍。 例如，级别`j`回答长度的跳跃`2^j`。 
2. 对于每个查询，使用决定操作顺序`c`。 如果`c = 0`，首先应用长度的左跳`a`，然后右跳长度`b`。 如果`c = 1`，先进行右跳。 
3. 进行长度跳跃`k`，检查二进制表示`k`。 对于设置的每一位，将当前站点替换为存储在该二进制提升级别的目的地。 每个设置位对应于路线的一个二的幂段。 
4. 输出两次跳转完成后到达的站点。 

为什么它有效：

 二进制提升背后的不变性是`up[j][v]`总是准确地代表`2^j`相同隧道功能的应用从`v`。 基础级别是通过构造而实现的，每个更高级别都是通过应用前一个跳跃两次而形成的，因此该属性适用于每个级别。 任何移动计数都可以使用二进制表示法分成 2 的幂，因此组合所选的跳跃会得到与单独执行所有移动完全相同的结果。 

## Python 解决方案```python
import sys
from array import array

input = sys.stdin.readline

def build_lift(n, nxt):
    LOG = 50
    lift = [array('i', nxt)]
    for _ in range(1, LOG):
        prev = lift[-1]
        cur = array('i', [0]) * (n + 1)
        for i in range(1, n + 1):
            cur[i] = prev[prev[i]]
        lift.append(cur)
    return lift

def jump(v, k, lift):
    bit = 0
    while k:
        if k & 1:
            v = lift[bit][v]
        k >>= 1
        bit += 1
    return v

def solve():
    n, q = map(int, input().split())
    left = [0] + list(map(int, input().split()))
    right = [0] + list(map(int, input().split()))

    left_lift = build_lift(n, left)
    right_lift = build_lift(n, right)

    ans = []
    for _ in range(q):
        x, a, b, c = map(int, input().split())
        if c == 0:
            x = jump(x, a, left_lift)
            x = jump(x, b, right_lift)
        else:
            x = jump(x, b, right_lift)
            x = jump(x, a, left_lift)
        ans.append(str(x))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```这`build_lift`函数为一个隧道方向创建表。 第一个数组是直接边，后面的每个数组通过将前一个数组与其自身组合来使跳转长度加倍。 使用`array('i')`这是故意的，因为 Python 列表将存储引用，并且会超出大约一千万个存储转换的内存限制。 

这`jump`函数跟随移动计数的位。 如果设置了当前位，则应用相应的预先计算的跳转。 移动计数适合 50 位，因为`2^50`大于`10^15`。 

查询处理只选择两个独立跳转的顺序。 的价值观`a`和`b`可以为零，并且`while k`循环自然会通过返回原始电台来处理这种情况。 

Python 整数不会溢出，因此大的移动计数是安全的。 唯一需要注意的索引细节是电台的编号从`1`，因此每个提升数组在位置处都包含未使用的元素`0`。

 ## 边缘情况

 单站图的两个隧道函数都指向自身。 升降台仅包含目的地`1`在各个层面。 一个查询`a = 0`和`b = 0`不执行跳跃并返回起始站。 具有巨大值的查询仍然返回`1`因为每个跳转级别都保留自循环。 

对于之前的自循环示例：```
2
1 1
2 2
2 1000000000000000 7 0
```左升降台发送站`2`到车站`1`处于零级，每个更高的级别也停留在车站`1`。 第一次左跳立即达到稳定循环，其余左跳不会改变结果。 最后的右跳使车站保持在`1`，生产：```
1
```对于顺序敏感的示例：```
3 1
2 3 3
1 1 2
1 1 1 0
```该算法首先应用左跳，到达站`2`，然后应用右跳，返回站`1`。 结果是：```
1
```相同的图表与`c = 1`首先应用右跳，到达车站`1`，然后向左移动至车站`2`。 这证实了该解决方案没有合并两个函数并保留了所需的操作顺序。
