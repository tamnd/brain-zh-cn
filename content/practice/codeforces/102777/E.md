 ## 问题理解

 计算器显示屏是三行文本绘图，其中每个字符占据固定的 3 x 3 区域。 屏幕包含数字、加号或减号以及最后的等号。 相邻符号由一空白列分隔。 任务是恢复写入的算术表达式，使用显示的运算从左到右对其求值，并以普通文本形式打印表达式，然后在等号后打印结果。 

输入大小以三个显示行的宽度来衡量，最多可达1000个字符。 这意味着整个屏幕仅包含几百个图块，因此算法应该对每个字符处理恒定的次数。 任何尝试对每个图块进行多种解释或重复扫描整个表达式的方法都是不必要的。 

各个数字的值足够小，普通整数算术就足够了。 主要的难点不是计算，而是正确识别七段式符号。 

有几个细节可能会破坏一个简单的实现。 前导减号是实数运算符，而不是第一个数字的一​​部分。 例如，显示代表`-10-7=`必须成为`-10-7=-17`， 不是`10-7=-3`。 另一个问题是等号。 它后面没有表达式，因此一旦找到它就应该停止解析。 第三个问题是数字可能包含多个数字，因此每个识别的数字都必须附加到当前数字，直到出现运算或等号。 

## 方法

 直接方法将尝试将每个可能的三列块与所有已知符号进行比较。 由于只有十个数字和几个运算符，因此这个强力解析器已经是正确的。 它的问题不在于比较的数量，因为可能的符号很少，但粗心的实现经常会犯在尝试分割表达式时重复搜索整个屏幕的错误。 宽度为 1000 时，仍然可以加快速度，但它不使用输入的结构。 

有用的观察结果是显示器已经被分成独立的图块。 每个图块都有固定的宽度，分隔符列始终为空。 这意味着整个问题简化为一次遍历瓷砖。 瓦片可以立即转换为符号，并且可以在构建生成的字符串时对其进行评估。 

算术部分有额外的简化。 该表达式仅包含加法和减法，因此没有优先级处理。 一旦令牌被恢复，该值只是一个累积和，当前符号应用于后面的每个数字。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(W) | O(W) | 如果认真执行即可接受 |
 | 最佳 | O(W) | O(W) | 已接受 |

 这里 W 是三个输入行的宽度。 最佳解决方案是干净的逐块解析器。 

## 算法演练

 1. 读取三个显示行并将它们填充到相同的长度。 输入已经代表了一个完整的屏幕，因此保持行对齐可以让每个图块按列位置提取。 
2. 从左向右移动屏幕并跳过完全空白的列。 这些列只是符号之间的分隔符。 
3. 对于每个非空图块，从所有三行中取出接下来的三列，并将生成的 3 x 3 模式与已知的数字和运算符模式进行比较。 这会将图形表示转换为普通字符。 
4. 根据识别的字符构建表达式字符串。 当到达等号时，停止，因为它后面的所有内容都不存在。 
5. 通过扫描字符来评估恢复的表达式。 保持当前符号和当前正在读取的数字。 当出现运算符时，将前一个数字与其符号相加，并更新下一个数字的符号。 
6. 打印恢复的表达式，等号后打印最终值。 

正确性来自于每个符号恰好占据一个独立的图块这一事实。 解析器永远不会猜测数字结束的位置，因为分隔符定义了所有边界。 由于图块字典包含所有可能的符号，因此每个提取的图块都会准确地转换为最初显示的字符。 评估阶段保留累加值等于所有完全处理项的值的不变量，而当前符号描述下一项。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

patterns = {
    "0": (" _ ", "| |", "|_|"),
    "1": ("   ", "  |", "  |"),
    "2": (" _ ", " _|", "|_ "),
    "3": (" _ ", " _|", " _|"),
    "4": ("   ", "|_|", "  |"),
    "5": (" _ ", "|_ ", " _|"),
    "6": (" _ ", "|_ ", "|_|"),
    "7": (" _ ", "  |", "  |"),
    "8": (" _ ", "|_|", "|_|"),
    "9": (" _ ", "|_|", " _|"),
    "+": ("   ", " _ ", "|_|"),
    "-": ("   ", "___", "   "),
    "=": ("   ", "___", "___"),
}

decode = {v: k for k, v in patterns.items()}

def solve():
    rows = [input().rstrip("\n") for _ in range(3)]
    width = max(map(len, rows))
    rows = [row.ljust(width) for row in rows]

    expr = []
    col = 0
    while col < width:
        if all(rows[r][col] == " " for r in range(3)):
            col += 1
            continue

        tile = tuple(row[col:col + 3].ljust(3) for row in rows)
        expr.append(decode[tile])
        col += 3

    expr = "".join(expr)

    value = 0
    current = 0
    sign = 1
    for ch in expr:
        if ch.isdigit():
            current = current * 10 + int(ch)
        else:
            value += sign * current
            current = 0
            sign = 1 if ch == "+" else -1
    value += sign * current

    print(expr + "=" + str(value))

if __name__ == "__main__":
    solve()
```字典存储每个可能符号的精确三行图。 这避免了在解析期间尝试手动重建段。 输入被填充，因为最终的图块可以恰好在最后一个字符处结束，并且超出当前行长度的切片将产生不一致的元组。 

解析器在读取符号后前进三列。 空白分隔符是单独处理的，因此不存在将间隙视为另一个字符的风险。 求值器不需要堆栈或优先规则，因为只存在加法和减法。 当前数字逐位累加，只有遇到运算或表达式结束时才提交。

 ## 边缘情况

 负结果不需要特殊解析。 对于诸如这样的表达式`3-10=`，解析器首先恢复字符`3-10`，然后评估器存储`3`，更改减号后的符号，然后减去`10`。 输出变为`3-10=-7`。 

具有多个数字的数字不得拆分为单独的操作数。 在表达式中`2+10=`, 数字图块`1`和`0`连续读取，因此当前数字从`1`到`10`在添加之前。 将每个图块视为单独的数字会错误地产生`2+1+0=3`。 

等号必须终止解析。 如果最后一个图块被误认为是运算符或操作数，则求值器可能会尝试处理等号后面不存在的值。 该算法通过解码完整的图块序列并仅使用等号作为显示表达式的结束标记来避免这种情况。 

输入末尾的空白分隔符列不得创建空符号。 解析器在尝试提取图块之前会跳过完全空的列，这样即使输入行用空格填充，也可以保持图块边界对齐。
