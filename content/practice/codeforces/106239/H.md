 ## 问题理解

 我们站在一排标记为 0 到 n 的位置上。 位置 0 是起点，没有奖励，而从 1 到 n 的每个位置，如果我们落在它上，都会贡献固定的能量值。 我们从位置 0 开始，想要到达位置 n。 

运动受到两种方式的限制。 每次移动都是向前迈出长度为 1 或 2 的一步。 但是，我们不能连续进行两次 1 步移动。 这会在上一个移动和下一个允许的移动之间创建依赖关系。 每次我们降落在位置 i 时，我们立即收集 Ei。 

任务是选择一个从 0 到 n 的有效跳跃序列，尊重“没有两个连续的 1 步”规则并最大化收集的总能量。 

约束 n ≤ 100000 意味着我们至少需要线性或接近线性的时间。 任何枚举路径的解决方案都是指数的，因为在每个位置我们都会分支为具有全局依赖性的两种移动类型，并且有效序列的数量像斐波那契式递归一样增长，但具有附加状态，因此暴力是不可能的。 即使是在不压缩状态的情况下尝试所有序列的简单动态编程也会重复相同的子问题。 

一个微妙的边缘情况来自于对连续 1 步的限制。 如果解决方案忘记了这种依赖性，它就会错误地将问题视为标准“爬升 1 或 2 步”DP 并过多计算无效转换。 另一种边缘情况是当 n 很小时，尤其是 n = 1 或 n = 2 时，“无连续 1 步”的规则不会完全激活，粗心的转换可能会索引越界或错过唯一的有效路径。 

例如，如果 n = 2 并且 E = [100, 1]，如果允许的话，最佳路径是 0 → 2，但根据解释，只有有效的移动才必须仔细检查，因为 0 → 1 → 2 由于连续的 1 步而被禁止，所以答案是 E2 = 1。 

## 方法

 暴力方法会尝试从 0 开始的所有可能的跳跃序列，跟踪当前位置以及最后的移动是 1 步还是 2 步。 在每个状态，我们都会分支到有效的动作并积累能量。 这是正确的，因为它探索所有合法路径并根据着陆位置精确地计算奖励。 问题是路径的数量随着 n 呈指数增长。 即使修剪了无效的连续 1 步转换，状态空间仍然会爆炸，因为每个位置都可以通过不同历史记录的多种方式到达，从而导致重复重新计算。 

关键的观察是，唯一重要的历史信息是先前的举动是 1 步还是 2 步。 整个问题归结为对具有两种状态的位置的动态规划。 一旦我们对这个状态进行编码，转换就变得本地化并且独立于完整的历史。 这将问题转化为线性动态规划，其中每个位置每个状态计算一次。 

我们定义 dp[i][0] 为最后一步为 1 步到达 i 时的最大能量，dp[i][1] 为最后一步为 2 步到达 i 时的最大能量。 该约束禁止通过另一个 1 步从 dp[i][0] 转换到 i+1，这自然会强制执行该规则。

 ## 算法演练

 我们维护一个按位置和最后移动类型索引的 DP 表。

1. 除起始状态外，将所有状态初始化为负无穷大。 在位置 0，我们从概念上从“无先前移动”状态开始，该状态允许将 1 步或 2 步作为第一个动作。 这避免了错误地限制第一次跳跃。 
2. 从每个位置 i，根据我们到达那里的方式考虑转换。 如果我们通过 1 步到达，那么下一步必须是 2 步，所以我们只过渡到 i+2。 如果我们通过 2 步到达，我们可能会转到 i+1 或 i+2。 这直接对规则进行编码并防止无效的连续 1 步序列。 
3. 当从 i 过渡到 j 时，我们将 Ej 添加到 DP 值，因为我们在着陆时收集能量。 这确保了每次着陆贡献都被计算一次。 
4. 我们以从 0 到 n 的递增顺序处理位置，因为所有转换都向前进行，因此较早的状态在使用之前已完全确定。 
5. 答案是 dp[n][0] 和 dp[n][1] 中的最大值，因为最后一种移动类型都可能达到 n。 

它的工作原理与状态压缩参数有关。 任何以 i 结束的有效路径都完全由其最佳分数和最后的移动类型来表征。 没有其他历史细节会影响未来的合法性或奖励，因此仅存储这两个状态可以保留最佳子结构。 每个转换都保留了可行性，并且每个可行路径都可以在 DP 中表示，因此不会错过任何候选解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    E = [0] + list(map(int, input().split()))

    NEG = -10**18

    dp = [[NEG, NEG] for _ in range(n + 1)]

    dp[0][0] = dp[0][1] = 0

    for i in range(n + 1):
        for last in (0, 1):
            if dp[i][last] == NEG:
                continue

            if i + 1 <= n:
                if last == 1:
                    dp[i + 1][0] = max(dp[i + 1][0], dp[i][last] + E[i + 1])
            if i + 2 <= n:
                dp[i + 2][1] = max(dp[i + 2][1], dp[i][last] + E[i + 2])

    print(max(dp[n][0], dp[n][1]))

if __name__ == "__main__":
    solve()
```DP 表明确区分了两个允许的“最后一步”状态。 转换逻辑强制执行规则：在 1 步（last = 0）之后，只允许进行 2 步，因此我们只更新 dp[i+2][1]。 经过 2 步（最后 = 1）后，两个转换均有效。 能量在到达时添加，确保每个位置在每条路径上贡献一次。 

初始化 dp[0][0] = dp[0][1] = 0 是一种建模技巧，允许第一步的行为一致而无需特殊情况。 由于位置 0 没有能量，因此不会扭曲总和。 

## 工作示例

 考虑样本输入 n = 5，E = [1, 10, 10, 10, 1]。 

我们只跟踪可达状态。 

| 我| dp[i][last=1]（最后两步）| dp[i][last=0]（最后一步）|
 | ---| ---| ---|
 | 0 | 0 | 0 |
 | 2 | 10 | 10 - |
 | 4 | 20 | - |
 | 5 | - | 21 | 21

 转换为 0 → 2 → 4 → 5。每次着陆时，我们都会添加能量：10 + 10 + 1 = 21。该表显示，只有 2 步转换占主导地位，因为该规则严重限制了连续的 1 步。 

现在考虑一个较小的情况 n = 4, E = [5, 100, 5, 100]。 

| 我| dp[i][最后=1] | dp[i][最后=0] |
 | ---| ---| ---|
 | 0 | 0 | 0 |
 | 2 | 100 | 100 - |
 | 3 | - | 105 | 105
 | 4 | 200 | 200 - |

 这里的最佳路径是 0 → 2 → 4，收集 100 + 100 = 200。任何提前插入 1 步的尝试都会阻止另一个 1 步并降低灵活性，而 DP 正确捕获了这一点。 

这些痕迹确认状态分割正确地表示了未来的移动选项如何仅依赖于最后一步。

 ## 边缘情况

 对于 n = 1，唯一有效的移动是直接到位置 1。DP 初始化 dp[0][*] = 0 并允许 2 步，但 i+2 无效，因此如果最后状态允许，则仅使用 i+1 转换。 该算法正确地产生 E1。 

对于 n = 2 且 E = [100, 1]，最佳路径避免 0 → 1 → 2，因为在 1 步之后，禁止再进行 1 步。 DP 只允许通过 2 步进行 0 → 2，产生值 1，这与最佳约束感知解决方案相匹配。 

对于所有值都相同的情况，DP 自然更喜欢更多的 2 步跳跃，因为它们不会降低未来的移动性。 例如，n = 4，所有 E = 10 都会产生 0 → 2 → 4，总共 20 个，而由于状态限制，永远不会构建无效链，并且 DP 正确地避免了过度计数。 

这些案例证实状态编码完全捕获了移动限制，而不需要更深入的历史记录。
