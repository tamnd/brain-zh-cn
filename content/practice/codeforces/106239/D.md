 ## 解决方案
 ## 问题理解

 该地图由来自的行组成`0`到`n+1`和列来自`1`到`m`。 行数`0`和`n+1`代表北极和南极。 每个补给点都位于行内`1...n`。 

来自细胞`(x,y)`我们可能会向南移动到`(x+1,y)`，或在同一行内左右移动。 列是循环的，所以列`1`与列相邻`m`。 

旅程从行的某个地方开始`0`，在行的某处结束`n+1`，并且必须至少访问每个供应点一次。 由于禁止向北移动，因此行将以非降序遍历。 我们想要最少的总步数。 

垂直运动实际上是固定的。 从行开始`0`划船`n+1`我们必须准确下降`n+1`次，无论选择哪条路线。 唯一的自由是每行内部执行多少水平移动。 

限制是巨大的。 两个都`n`和`m`可以达到`10^9`，因此网格本身无法被存储。 所有测试用例的供电点数量最多为`10^6`，这意味着需要一种在点数上接近线性的算法。 任何涉及对列或行进行动态编程的方法都将立即变得不可能。 

一个微妙的点是没有补给点的行并不重要。 穿过它们只会导致强制性的向下移动。 另一个微妙之处是列的循环性质。 例如，与`m=10`，从列移动`1`到专栏`10`花费一步，而不是九步。 

考虑```
1
1 10 2
1 1
1 10
```答案是`3`。 

我们从行开始`0`，选择列`1`, 向下至`(1,1)`，向左移动一次到`(1,10)`，然后下到南极。 列的线性解释会错误地给出成本`11`。 

另一个棘手的情况是```
1
3 10 3
1 2
1 8
3 5
```第一行需要访问列`2`和`8`。 因为柱子形成一个循环，所以最便宜的方法是遍历区间外较短的弧，不一定直接从`2`到`8`。 

## 方法

 一个蛮力的想法是将每个列视为一个状态。 处理完一行后，我们保持每列结束的最小成本。 对于包含多个供应点的行，转换模拟访问所有供应点。 

这是有效的，因为行的顺序是固定的，并且只有结束列会影响未来的决策。 很遗憾`m`或许`10^9`，因此维持每列一个值是没有希望的。 

关键的观察结果是，只有包含补给点的行才会影响水平移动。 在这样的行内，如果最左边和最右边的供应列是`L`和`R`，每条有效路径必须覆盖它们之间的所有点。 由于所有点都位于一个圆上，因此访问每个点相当于访问两个极端。 

假设我们在某列输入该行`p`。 访问完每一个点后，最终的位置只需要是两个极端之一，`L`或者`R`。 任何在其他地方结束的解决方案都可以通过继续到最近的极端来缩短。 因此，每一行仅贡献两个状态。 

这将问题简化为包含供应品的行的动态编程问题。 如果有`s`对于这样的行，我们保持在其左端点或右端点完成当前行的最小成本。 自从`s≤k`，复杂度变为线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(公里) | O(米) | 太慢了|
 | 最佳| O(k log k) | O(k log k) | O(k) | 已接受 |

 对数因子来自按行对供应点进行排序。 

## 算法演练

 ### 1. 按行对补给点进行分组

 按行对所有补给点进行排序。 对于包含至少一个点的每一行，仅记录最小列`L`和最大列`R`。 

中间点是无关紧要的，因为覆盖两个极端的任何路径都会自动覆盖该行的所有供应点。 

### 2.为每个已处理行定义两个状态

 对于每个活动行，维护`dpL`：当我们在列处完成此行时，到目前为止累积的最小水平成本`L`。`dpR`：当我们在列处完成此行时，到目前为止累积的最小水平成本`R`。 

垂直运动将单独添加，因为它总是`n+1`。 

### 3. 处理第一个活动行

 在进入第一行之前，我们可以从北极的任何一列开始。 因此可以自由选择输入栏。 

覆盖区间`[L,R]`在圆上，我们遍历较短的补弧。 参观一切并结束于的费用`L`等于```
circle_distance(L,R)
```类似地结束于`R`。 

对于只有一个点的行，两个成本都为零。 

### 4. 连续活动行之间的转换

 假设前一行极值是`(L1,R1)`当前行极值是`(L2,R2)`。 

计算结束于的成本`L2`，我们考虑四种可能性：

 开始于`L1`或者`R1`，从该列输入新行，访问间隔中的所有列，最后停在`L2`。 

对于结束于的情况也是如此`R2`。 

圆上两列之间的水平距离为```
dist(a,b)=min(|a-b|,m-|a-b|)
```在当前行内，如果我们从列开始`p`并希望结束于`L2`，我们必须首先达到`R2`，因为必须访问两个极端。 成本变为```
dist(p,R2)+linear_length
```在哪里```
linear_length=R2-L2
```同样，结束于`R2`成本```
dist(p,L2)+linear_length
```原因是，选择一个极端作为最终位置后，就必须先访问另一个极端。 

### 5. 对所有活动行重复此操作

 逐行更新两个状态值。 

### 6.添加垂直移动

 从行降序`0`划船`n+1`总是要求准确`n+1`步骤。 

最终的答案是```
n+1+min(dpL,dpR)
```### 为什么它有效

 处理完一行后，与未来行相关的唯一信息是我们当前站在哪个极端列以及到达它的最低成本。 该行的每个供给点都位于两个极端之间，因此任何有效的遍历都可以重新排列为在极端处结束的遍历，而无需增加距离。 这给出了每行恰好有两个状态的最佳子结构。 由于所有转换都考虑了每个可能的先前极端，因此动态规划会探索每个最佳路线。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**18

def dist(a, b, m):
    d = abs(a - b)
    return min(d, m - d)

t = int(input())
ans = []

for _ in range(t):
    n, m, k = map(int, input().split())

    rows = {}

    for _ in range(k):
        x, y = map(int, input().split())
        if x not in rows:
            rows[x] = [y, y]
        else:
            rows[x][0] = min(rows[x][0], y)
            rows[x][1] = max(rows[x][1], y)

    items = sorted(rows.items())

    first_L, first_R = items[0][1]
    width = first_R - first_L

    dpL = width
    dpR = width

    prevL, prevR = first_L, first_R

    for _, (curL, curR) in items[1:]:
        width = curR - curL

        ndpL = min(
            dpL + dist(prevL, curR, m) + width,
            dpR + dist(prevR, curR, m) + width
        )

        ndpR = min(
            dpL + dist(prevL, curL, m) + width,
            dpR + dist(prevR, curL, m) + width
        )

        dpL, dpR = ndpL, ndpR
        prevL, prevR = curL, curR

    ans.append(str(n + 1 + min(dpL, dpR)))

print("\n".join(ans))
```该字典仅存储实际包含补给点的行。 对于每个这样的行，我们只保留最左边和最右边的列。 

动态编程变量表示迄今为止累积的最小水平距离。 过渡期间忽略垂直距离，因为它是恒定的并且等于`n+1`。 

当移动到新行时，以左端结束意味着必须首先访问右端。 因此，过渡使用距离`curR`加上间隔宽度。 以右端结束的公式是对称的。 

所有值都很容易适合 64 位整数，但使用 Python 整数可以完全避免溢出问题。

 ## 边缘情况

 考虑```
1
1 10 2
1 1
1 10
```行极值是`1`和`10`，给出宽度`9`。 没有其他行包含耗材。 横向成本等于`9`，垂直成本等于`2`，答案是`11`。 

一个常见的错误是认为环绕可以让我们用成本覆盖两个端点`1`。 如果我们只需要在它们之间移动，则确实如此，但是覆盖它们之间的每一列都需要遍历间隔本身。 

另一个例子是```
1
4 20 3
1 5
3 10
3 15
```第 1 行有一个点，因此两个状态都为零。 第 3 行有间隔`[10,15]`， 宽度`5`。 转换正确地考虑了从列接近任一端点`5`。 答案仍然是最优的，因为只有之前的极端位置才重要。 

最后，```
1
5 1000000000 2
1 1
5 1000000000
```柱间圆距`1`和`10^9`是一。 该算法使用以下方法计算此值```
min(|a-b|, m-|a-b|)
```这避免了将圆视为直线。 线性距离公式会高估成本近乎`10^9`。
