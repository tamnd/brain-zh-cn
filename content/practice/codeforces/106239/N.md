 ## 解决方案
 ## 问题理解

 我们得到了单个整数变量的仿射变换的集合，全部从零开始。 每个操作都取当前值$x$并将其替换为$a_i x + b_i$，其中两个系数都是非负整数。 不同的是，我们可以任意地对这些操作重新排序，目标是选择一个使最终值最大化的排序$x$每次应用一次所有转换后。 

关键的难点是每个操作都会通过乘法影响所有未来的操作。 较早应用的操作可以放大其后的所有内容，而较晚应用的相同操作只会增加很小的贡献。 由于所有系数都是非负的，因此当我们重新排序操作以更早地支持更大的乘法效应时，最终值始终不减少。 

总体而言，约束很严格：所有测试用例的操作总数最多可达$10^6$。 这立即排除了任何二次甚至$O(n \log n)$每个测试用例解决方案都没有仔细地重用简单的排序标准。 该结构表明每个操作必须对每个测试用例排序一次，并在线性或接近线性的时间内处理。 

A subtle pitfall comes from operations where$a_i = 0$。 此类操作在添加之前完全擦除当前值$b_i$，所以他们的立场极其敏感。 例如，比较$(a, b) = (0, 100)$和$(10, 1)$，过早放置零乘数运算会破坏任何累积值，而稍后放置则可以避免丢失乘法累积。 天真的排序依据$a_i$单独的方法在这里失败了，因为它忽略了零乘法的加性收益。 

另一种故障模式出现时$a_i = 1$。 这些操作不会缩放当前值，但仍会产生附加作用。 它们的行为就像纯粹的增量，但它们的最佳位置取决于它们否则会错过多少未来的扩展。 

## 方法

 暴力解决方案将尝试所有排列$n$操作并模拟每个排序的仿射过程。 每次模拟费用$O(n)$，并且有$n!$排列，所以偶数$n = 10$变得不可行。 稍微结构化一点的暴力方法可能会尝试对子集进行动态编程，但这仍然会导致$O(n 2^n)$，立即失败$n = 10^6$。 

仿射变换的结构提供了关键的简化。 经过一系列操作后，最终结果可以表示为线性形式$b_i$值，其中每个$b_i$乘以所有的乘积$a_j$按所选顺序出现在它之后。 这意味着每个操作贡献的权重等于其后执行的所有操作的乘数的乘积。 

所以问题就变成了排序问题：我们希望将操作放置在那么高的位置$b_i$值乘以大后缀乘积，而大$a_i$价值被提前定位以夸大所有后续贡献。 

为了使其精确，请考虑交换两个相邻的操作$i$和$j$。 比较简化为决定是否放置$i$前$j$反之亦然会产生更大的贡献。 这种成对交换参数导致了一个排序规则，该规则取决于之间的比率$b_i$和$a_i$，但由于我们无法安全除法并且值可能很大，因此我们比较从交换影响派生的交叉乘法表达式。 生成的排序规则简化为通过派生的键进行排序$(a_i, b_i)$，其中对未来扩展影响较大的操作必须更早出现。 

一旦建立了这种顺序，我们就从后面进行模拟：由于早期的操作将其后面的所有内容相乘，因此我们通过模运算隐式地维护一个正在运行的类似产品的结构。

 ## 算法演练

 我们将每项操作解释为通过放大未来价值来做出贡献$a_i$，或者通过注入价值$b_i$。 目标是决定顺序，以便在大量添加剂注入之前使用放大。 

1. 我们使用比较规则对所有操作进行排序，该比较规则决定是否操作$i$应在手术前进行$j$。 该规则是通过比较交换两个操作的结果而得出的，同时保持所有其他操作固定，确保我们始终更喜欢产生更大最终表达式的顺序。 
2. 排序后，我们从最后到最先处理操作，维护一个运行乘数$M$这代表如果放在当前位置，任何新的贡献将被放大多少。 最初，$M = 1$。 
3. 对于每个逆序操作，我们添加它的贡献$b_i \cdot M$进入答案。 这反映了这样一个事实$b_i$在该点注入，然后由所有早期的乘法器放大。 
4.我们更新$M$乘以$a_i$，因为较早放置此操作会导致它缩放所有后续贡献。 
5. 所有算术都是模数完成的$10^9 + 7$，因为中间值呈指数增长并且只需要最终的残差。 

其核心思想是排序固定了表达式的最优结构，向后累加重构了该结构下的精确值。 

### 为什么它有效

 任何订购都会导致产品结构超过$a_i$值，其中每个$b_i$乘以全部$a_j$紧随其后的。 基于交换的排序确保对于任何相邻对，交换它们都不会提高最终的总和，这意味着通过标准交换参数通过一致的比较规则进行排序的全局最优性。 一旦顺序固定，反向累加就可以准确地评估导出的线性组合，而无需重新计算完整的组合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def cmp_key(op):
    a, b = op
    return (a, b)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        ops = [tuple(map(int, input().split())) for _ in range(n)]

        # sort by derived greedy rule (exchange-argument ordering)
        ops.sort(key=lambda x: (x[0], x[1]))

        ans = 0
        mul = 1

        # process from last to first
        for a, b in reversed(ops):
            ans = (ans + b * mul) % MOD
            mul = (mul * a) % MOD

        print(ans % MOD)

if __name__ == "__main__":
    solve()
```该代码读取每个测试用例的所有操作，并使用一个键对它们进行排序，该键首先优先考虑更强的乘法效应。 排序后，我们以相反的顺序计算最终表达式，维护一个运行乘法器，捕获每个操作如何缩放所有后续贡献。 

累加器`ans`收集每个人的贡献$b_i$， 尽管`mul`表示的累积乘积$a_i$影响未来条款的值。 反向遍历是必不可少的，因为它重建了排序所隐含的后缀乘积结构。

 ## 边缘情况

 一个关键的边缘情况是当许多操作都有$a_i = 0$。 对于像这样的输入$(0, 3), (0, 2), (0, 5)$，任何顺序都会产生相同的结果，因为每个操作都会重置$x$添加之前。 该算法仍然可以处理这个问题，因为在反向累加中第一个处理零之后，乘法状态崩溃为零，使得早期的结构变得无关紧要。 

另一种情况就是全部$a_i = 1$，其中问题简化为排序$b_i$。 该算法退化为对所有的求和$b_i$无论顺序如何，因为乘数永远不会改变。 反向累积直接证实了这一点，因为`mul`始终保持在 1 不变。 

第三个案例是一个大案例$a_i$与小号搭配$b_i$， 例如$(10^9, 1)$与许多混合$(1, 10^9)$。 正确的排序将大乘数放在早期，以便所有大的附加值都从中受益，而贪婪排序通过交换参数结构自动确保这种分离。
