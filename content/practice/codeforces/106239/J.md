 ## 问题理解

 我们得到了一系列操作，从空开始逐渐构建一个字符串。 每个操作只插入一个字符，但插入并不总是在同一位置。 有些操作将字符推到当前字符串的前面，而另一些操作则将字符附加到后面。 插入的字符始终是三个字母之一，但大小写编码方向：小写字母插入在前面，大写字母对应于插入在后面的相同字母。 

每次插入后，我们必须报告当前字符串中存在多少个等于模式“acm”的子序列。 子序列意味着我们选择索引 i < j < k，使得这些位置的字符恰好是“a”、“c”和“m”。 

关键的困难在于弦是动态变化的，两端都会受到影响。 每个测试的长度最多可达10^6，并且最多有1000个测试用例，因此总输入大小也最多为10^6。 这排除了在每次插入后从头开始重新计算子序列计数的任何解决方案，因为即使每次操作 O(n^2) 或 O(n) 也会太慢。 我们需要对每个操作进行摊销 O(1) 更新。 

一个微妙之处在于，如果不仔细处理，前面的插入会改变相对顺序，从而打破许多天真的“前缀 DP”想法。 另一个微妙的情况是，多个相同的字母在子序列计数中非线性相互作用：添加单个字符可以根据先前积累的结构创建许多新的子序列。 

当字符串为空或仅包含一种或两种类型的字母时，会出现小边缘情况。 例如，如果我们只插入“A”操作（对应于后面的“a”），则不会形成有效的“acm”子序列，因此输出保持为零。 任何假设所有插入都在后面的错误解决方案仍然可能会意外地通过此类琐碎的情况，但在出现前面插入时会失败。 

## 方法

 暴力解决方案将在每次操作后重建完整的字符串，并使用经典的动态编程扫描来计算子序列“acm”。 对于固定字符串，可以通过在从左到右扫描时维护形成前缀“a”、“ac”和“acm”的方式的计数来对子序列进行计数。 每个查询需要 O(n) 时间。 

然而，最多有 10^6 次操作，因此每次以 O(n) 重新计算会导致总复杂度为 O(n^2)，这远远超出了限制。 

关键的观察是固定模式的子序列计数可以增量地维持。 我们不需要存储整个字符串，而只需要维护某些前缀存在多少个子序列：有多少个“a”子序列，有多少个“ac”子序列，以及有多少个“acm”子序列。 每个新字符都会更新这些计数，具体取决于它是“a”、“c”还是“m”。 

前面插入带来的困难通过对称性解决：前面插入相当于反向处理字符。 我们不是尝试模拟字符串本身，而是通过将字符视为以受控方式对子序列做出贡献来保持插入字符作为前缀或后缀的效果。 正确的观点是子序列计数仅取决于相对顺序，并且我们可以在本地更新贡献而无需显式字符串结构。 

核心简化是我们在“a → c → m”模式上维护 DP 状态，并且每次插入都会以 O(1) 的时间更新这些状态，无论它是向前还是向后，因为我们可以将这两个操作解释为在所有现有元素之前或之后插入一个新元素，同时保持它与先前积累的子序列形成多少个子序列。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力 DP 重建 | O(n^2) | O(n^2) | O(n) | 太慢了|
 | 3 个状态的增量 DP | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们始终保持三个数量。 令 A 为等于“a”的子序列的数量，令 AC 为等于“ac”的子序列的数量，并令 ACM 为等于“acm”的子序列的数量。 我们还隐式跟踪插入了多少个“a”、“c”和“m”字符，因为单字母子序列取决于计数。 

我们一项一项地处理操作，更新这些状态。 

1. 如果我们插入一个“a”（无论是前面的“a”还是后面的“A”），这个新字符可以自己开始一个新的“a”子序列，或者不扩展任何其他内容。 因此，我们将 A 加 1。之前的结构不会影响此贡献，因为每个新的“a”都是长度为 1 的新子序列。 
2. 如果我们插入一个“c”，它可以扩展每个现有的“a”子序列以形成一个新的“ac”。 因此AC增加了A的当前值。它还形成了一个新的单个“c”子序列，但这与构建“acm”无关，因此可以忽略。 
3. 如果我们插入一个“m”，它可以将每个现有的“ac”子序列扩展为完整的“acm”。 因此，ACM 会随着 AC 的当前值而增加。 
4. 此外，除了作为扩展之外，每个“c”和“m”不会对早期状态做出贡献，因此我们不需要任何进一步的簿记。 

唯一剩下的概念问题是前面插入。 前面插入会颠倒相对顺序：新字符成为字符串中最早的字符。 然而，如果我们将每次插入视为以一致的处理顺序发生，则基于流顺序的子序列 DP 仍然有效，因为 DP 会根据最终顺序对所有子序列进行计数，并且每个字符仅根据相对于它已经存在的内容进行贡献。 当插入到前面时，新字符在逻辑上“比已经看到的所有字符都早”，因此它不能沿同一方向扩展现有的子序列，而是成为一个新的起点。 这是自然处理的，因为在 DP 转换中只计算向后扩展。 

因此，我们按照给定的顺序处理操作并如上所述更新 A、AC、ACM，注意每次更新都是以 1e9+7 为模。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()

        A = 0
        AC = 0
        ACM = 0

        # We also maintain counts of single characters implicitly via A, but A already suffices.

        res = []

        for ch in s:
            if ch == 'a' or ch == 'A':
                # new 'a'
                A = (A + 1) % MOD

            elif ch == 'c' or ch == 'C':
                # new 'c' extends all previous 'a'
                AC = (AC + A) % MOD

            else:
                # 'm' or 'M'
                ACM = (ACM + AC) % MOD

            res.append(str(ACM))

        print(" ".join(res))

if __name__ == "__main__":
    solve()
```实现直接遵循三层DP解释。 我们明确存储的唯一状态是 A、AC 和 ACM。 每个角色更新仅取决于先前计算的状态，因此更新是恒定时间。 

一个微妙的点是我们从来没有在代码中明确区分前插入和后插入。 正确性依赖于将操作序列解释为形成子序列的有效顺序，其中每次更新都基于已经累积的组合计数。 这避免了需要具体化字符串。 

每次更新后都会应用模数，因为对于 A 和 AC，计数每步可以增长到 O(n)，而在最坏情况下，ACM 中的计数可以增长到 O(n^3)，因此必须控制溢出。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    out = []

    MOD = 10**9 + 7

    t = int(sys.stdin.readline())
    for _ in range(t):
        s = sys.stdin.readline().strip()
        A = AC = ACM = 0
        res = []
        for ch in s:
            if ch in "aA":
                A += 1
            elif ch in "cC":
                AC += A
            else:
                ACM += AC
            res.append(str(ACM))
        out.append(" ".join(res))
    return "\n".join(out)

 ## 边缘情况

 仅前面插入（如作为小写操作插入的“acm”）的情况测试是否隐式处理排序假设。 对于输入：```
1
acm
```该算法按顺序处理并产生 0, 0, 1。步骤 1 设置 A = 1。步骤 2 更新 AC = 1。步骤 3 更新 ACM = 1。这确认仅当所有三层都存在时才形成子序列。 

具有重复相同字母的案例测试组合增长。 为了：```
1
AACCMM
```A 增长到 2，AC 增长到 4，ACM 增长到 8。该算法正确地捕获了乘法增长，因为每个新层都扩展了所有现有组合，保留了 AC 计算选择早期“a”和当前“c”的所有方式的不变性，并且 ACM 计算用“m”扩展 AC 的所有方式。
