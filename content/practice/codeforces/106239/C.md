 ## 解决方案
 ## 问题理解

 我们得到一个正整数序列，并被要求回答多个独立的查询。 每个查询提供一个目标值$x$，并且我们必须确定是否存在一个连续的子数组，其元素相乘恰好等于$x$。 

换句话说，对于每个查询，我们检查数组是否包含其乘积等于给定数字的段。 段必须是连续的，不同的查询是相互独立的。 

约束表明所有测试用例的总数组长度最多为$2 \cdot 10^5$，并且查询总数也最多为$2 \cdot 10^5$。 这立即排除了任何针对每个查询从头开始重新计算子数组乘积或为每个查询独立显式枚举所有子数组的解决方案。 任何每个测试用例都是二次的方法都会达到大约$10^{10}$在最坏的情况下进行操作，这远远超出了可行的范围。 

微妙的困难不仅在于子阵列的数量，还在于产品的大小。 即使是中等长度的子数组也会溢出典型的整数边界，因此任何不提前停止的简单乘法不仅速度慢，而且在数值上也不安全。 

一些边缘情况值得牢记。 

如果数组包含很多，例如$a = [1, 1, 1, 1]$，那么每个子数组都有乘积 1。尝试“增长”乘积的简单方法可能会过度循环而不会取得进展，因为乘以 1 不会改变值。 

如果查询请求的值不显示为任何子数组乘积，例如$x = 12$在一个像这样的数组中$[2, 3, 6, 1, 4]$，那么许多子数组部分匹配$x$，但不存在完全匹配。 任何仅检查整除性或部分因子匹配而不进行全面验证的方法都可能错误地接受此类情况。 

最后，由于所有数字都是正数，一旦运行的产品超过$x$，它只会进一步增加，这提供了正确解决方案必须利用的强大修剪机会。 

## 方法

 最直接的想法是枚举每个子数组并计算其乘积。 对于每个起始索引$l$，我们扩展$r$向右，将元素相乘，直到我们匹配$x$或产品超过它。 如果我们准确击中$x$，我们可以提前停止该查询。 

这种方法是正确的，因为它明确地检查每个可能的候选片段。 然而，它的最坏情况行为是每个测试用例的二次方。 如果数组很大并且包含很多类似的小值，那么乘积会在很长一段时间内保持很小，并且每个起始位置可能会扫描几乎整个后缀。 这导致大约$O(n^2)$每次测试的乘法，这对于$n$最多$2 \cdot 10^5$在所有测试中。 

关键的观察是我们不需要独立考虑所有查询的所有子数组。 对于固定的起始索引，一旦产品超过该测试用例中的最大查询值，我们就可以安全地停止扩展。 由于所有数字都是正数，因此当我们扩展段时，乘积是单调的，因此没有进一步的扩展可以将其恢复到有效值。 

这使我们能够针对每个起始位置预先计算所有可到达的子数组乘积，直到合理的截止值，并将它们存储在哈希集中。 然后每个查询就变成一个简单的成员资格检查。 

尽管理论上这仍然具有最坏情况的二次结构，但乘积的单调增长确保了在实践中许多段提前终止，尤其是当值很大时。

 ## 算法演练

 我们独立处理每个测试用例。 

1.读取数组和所有查询，并计算最大查询值$X_{\max}$。 该值充当乘积扩展的截止值，因为任何大于此值的子数组乘积都无法帮助回答任何查询。 
2. 初始化一个空散列集，该散列集将存储所有作为有效候选者的子数组乘积。 
3. 对于每个起始索引$l$，将正在运行的产品初始化为1。 
4. 延伸右端点$r$从$l$到$n$，将当前乘积乘以$a[r]$。 一旦产品超过$X_{\max}$，我们停止从此延伸$l$，因为进一步的扩展只能增加它。 
5. 每次更新产品时，我们都会将其插入集合中。 这确保了截止之前的每个可到达的子阵列乘积都被记录。 
6. 预处理完所有起点后，通过检查查询值是否存在于集合中来回答每个查询。 

正确性取决于每个有效子数组被视为一对的事实$(l, r)$，并且我们永远不会错过有效的产品，因为只有当超过对任何查询都无用的值时，我们才会停止扩展。 

### 为什么它有效

 对于任何固定的起始索引，当我们向右延伸时，乘积序列是严格非递减的，因为所有元素都是正数。 这保证了一旦产品超过$X_{\max}$，没有进一步的扩展可以产生与任何查询匹配的值。 因此，修剪不会消除任何潜在的有效答案。 由于每个子数组都是从一个起始点生成的，因此相关范围内的所有可能的产品都包含在该集合中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        queries = [int(input()) for _ in range(q)]

        x_max = max(queries)

        seen = set()

        for l in range(n):
            prod = 1
            for r in range(l, n):
                prod *= a[r]
                if prod > x_max:
                    break
                seen.add(prod)

        out = []
        for x in queries:
            out.append("YES" if x in seen else "NO")
        print("\n".join(out))

if __name__ == "__main__":
    solve()
```核心结构是在起始位置和结束位置上的双循环，但当运行的产品超过最大查询值时会硬中断。 这个截止点是必要的； 如果没有它，解决方案将立即超时。 

哈希集存储所有可到达的产品，并且每个查询减少为恒定时间的成员资格检查。 该解决方案依靠 Python 的大整数来安全地处理中间乘法，而无需担心溢出。

 ## 边缘情况

 当数组完全由 1 组成时，每个扩展都会保持乘积不变。 该算法仍然正确地为每个子数组插入值 1，并且在集合中永远找不到大于 1 的查询。 

对于单元素数组，仅存在长度为1的子数组，因此该算法每次开始仅产生一个乘积，这直接符合正确性条件。 

当所有元素都相等且大于 1 时，产品会随着我们的扩展而呈指数级增长。 这使得剪枝变得有效，并确保内部循环快速终止，从而防止实践中出现二次爆炸。
