 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，并要求选择一个连续的段，以便该段内最大和最小元素之间的差异尽可能大。 除了这个最大差异的值之外，我们还必须输出实现它的一个段。 

输入是长度最大为 100 的单个数组，每个值都在 0 到 100 之间。有效答案是任何索引对$l, r$这样子数组$A[l..r]$最大可能值为$\max(A[l..r]) - \min(A[l..r])$。 

约束条件$n \le 100$已经表明三次甚至二次解是可以接受的。 线性或线性算术解也可以，但没有必要。 关键的观察结果是，问题并不要求像特殊的单调属性或动态状态这样的独特结构，而只要求所有子阵列的全局最优。 

一个微妙的点是，最优分段不一定是唯一的，多个分段可能达到相同的最大差异。 任何一个有效的片段都是可接受的，这意味着我们不需要超出正确性的平局规则。 

一个天真的但常见的错误是假设最佳段必须包括整个数组的全局最小值或全局最大值。 这对于这个问题来说是正确的，但需要通过枚举逻辑而不是假设来证明。 

例如，考虑：```
A = [2, 3, 4, 1]
```最好的段是整个数组，最大为 4，最小为 1，差异为 3。错误的做法是选择像 [2, 3, 4] 这样的段，其差异为 2，忽略了扩展以包含 1 可以改善结果的事实。 

另一个边缘情况是所有元素都相等时：```
A = [5, 5, 5]
```每个段的差值为 0，因此任何单个元素段都是有效的。 简单的解决方案可能仍会不必要地返回较长的段，但正确性不受影响。 

## 方法

 最直接的解决方案是枚举每个可能的子数组。 对于每对索引$l, r$，我们扫描子数组以计算其最小值和最大值，然后如果此差异改善了当前最佳答案，则更新最佳答案。 

这是有效的，因为它明确评估每个候选细分的目标函数。 正确性是立即的：没有遗漏任何子数组。 

然而，成本很高。 有$O(n^2)$子数组，并计算每个片段的最小值和最大值$O(n)$，导致$O(n^3)$总操作。 尽管$n = 100$使这个边界但仍然可以接受，它不必要地慢。 

我们可以通过重用计算来改进这一点。 如果我们修复左端点$l$，我们可以扩展右端点$r$增量，同时在恒定时间内保持当前最小值和最大值。 每个扩展都会更新答案$O(1)$，将整体复杂度降低到$O(n^2)$。 

关键思想是从头开始为每个段重新计算最小值和最大值是多余的。 由于具有相同左端点的段形成了一个不断增长的序列，因此我们可以在扩展时保持状态。 

这将问题变成了一个两层循环，其中外层循环固定起点，内层循环延伸终点，同时保持运行极值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(1) | O(1) | 可以接受但缓慢|
 | 通过运行最小值/最大值进行扩展 | O(n²) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化变量来存储迄今为止找到的最佳答案：最佳差异、最佳左索引和最佳右索引。 我们从一个非常小的最佳差异开始，以便任何实际的细分都可以改进它。 
2. 修复左端点$l$从 1 到$n$。 这代表候选子数组的开始。 每个有效的子数组都必须从某个地方开始，因此我们系统地尝试所有可能性。 
3. 对于每个$l$,初始化两个变量`cur_min`和`cur_max`到$A[l]$。 这表示仅由位置处的单个元素组成的子数组的状态$l$。 
4. 延伸右端点$r$从$l$到$n$, 更新`cur_min = min(cur_min, A[r])`和`cur_max = max(cur_max, A[r])`。 这保持了当前子数组的正确极值而无需重新计算。 
5. 计算当前差值`cur_max - cur_min`。 如果这大于迄今为止的最佳差异，请将存储的答案更新为$(l, r)$以及新的差异。 
6. 继续扩展，直到全部$r$为此的值$l$处理完毕，然后进入下一步$l$。 
7. 所有迭代结束后，输出存储的最佳片段及其差值。 

### 为什么它有效

 每一步延伸$r$，算法保持当前子数组的精确最小值和最大值$[l, r]$。 这是更新规则保留的一个不变量：添加一个元素只需要将其与先前的极值进行比较。 由于每个子数组都由某个对唯一表示$(l, r)$，并且每个这样的对都被评估一次，算法会考虑所有候选者，而不会重复或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    best_diff = -1
    best_l, best_r = 0, 0
    
    for l in range(n):
        cur_min = a[l]
        cur_max = a[l]
        
        for r in range(l, n):
            if r > l:
                cur_min = min(cur_min, a[r])
                cur_max = max(cur_max, a[r])
            
            diff = cur_max - cur_min
            if diff > best_diff:
                best_diff = diff
                best_l = l
                best_r = r
    
    print(best_l + 1, best_r + 1, best_diff)

if __name__ == "__main__":
    solve()
```代码直接实现了两层枚举策略。 外循环固定左边界，内循环扩展右边界，同时保持运行的最小值和最大值。 输出时需要 +1 移位，因为该问题使用基于 1 的索引，而 Python 数组是基于 0 的。 

一个常见的实施陷阱是重新初始化`cur_min`和`cur_max`在内循环中错误地使用，这会破坏增量优化。 另一个微妙的问题是在计算差异之前更新极值，这必须以正确的顺序进行以确保包含当前元素。

 ## 边缘情况

 对于像这样的单元素数组`A = [7]`，算法集`cur_min = cur_max = 7`并立即评估差异 0。由于不存在其他段，因此它正确输出`(1, 1, 0)`。 

对于像这样的全相等数组`A = [3, 3, 3, 3]`，每次迭代都维持`cur_min = cur_max = 3`无论扩展。 差异永远不会超过 0，因此第一段`(1, 1)`保留存储的答案。 

对于像这样的严格递增数组`A = [1, 2, 3, 4]`，第一个外循环已经发现扩展到整个范围会产生最大差异。 该不变量确保一旦包含两个极端，后面的段就不能超过该值，因为所有未来的子数组都是子集或相等范围的变体。
