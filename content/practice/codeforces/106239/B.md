 ## 解决方案
 ## 问题理解

 我们有一个 1000 x 1000 的网格，具有固定的棋盘着色。 当 x + y 为偶数时，单元格 (x, y) 为白色，否则为黑色。 每个测试用例给出两个整数 a 和 b，我们必须决定是否可以选择一组连接的单元格，使得该组恰好包含一个白色单元格和恰好 b 个黑色单元格。 如果可能的话，我们必须通过列出其坐标来输出任何此类连接集。 

连接性是标准的 4 向邻接，因此任何两个选定的单元格必须可以通过逐步穿过选定集合内的共享边来相互访问。 关键的困难在于，我们不仅要选择两种颜色的任意计数，还要强制所选单元格形成一个连通分量。 

约束的总大小很大，但每个测试用例都是独立的，并且所有 a + b 的总和最多为 10^6，这强烈表明我们必须在其大小的线性时间内显式构造每个组件。 任何涉及每个测试用例整个 1000 x 1000 网格的搜索都是不必要的，而且如果重复的话会太慢。 

一个微妙的限制是网格是二分的。 这立即意味着任何连接区域的行为就像从起始单元开始的类似路径的扩展，其中每一步都会翻转颜色。 这限制了我们匹配任意 (a, b) 对的灵活性。 

主要的边缘情况来自不平衡。 如果 a 或 b 为零，我们被迫仅使用一种颜色，但棋盘网格中的单色诱导子图完全断开，因为相同颜色的单元永远不会正交接触。 因此，除非计数恰好为 1，否则任何 a > 0 且 b = 0 的情况（反之亦然）都是不可能的。 

当尝试贪婪地扩展路径而不确保剩余目标颜色分布的连通性时，会出现另一种失败模式。 一种幼稚的方法可能会盲目地交替颜色，但我们实际上需要一种允许控制一种颜色的剩余的结构。 

## 方法

 一个蛮力的想法是尝试通过 BFS 从每个起始单元构建连接组件，跟踪我们选择了多少个白色和黑色单元，并在匹配 (a, b) 时停止。 这在概念上是正确的，因为 BFS 枚举了所有连接的形状，但它是完全不可行的：每个 BFS 探索最多 10^6 个节点，并且对许多开始或许多测试用例执行此操作会导致二次行为。 

关键的观察是网格是规则的和二分的，因此我们构建的任何连接的形状都可以被视为一棵正在生长的树。 我们没有搜索网格，而是明确地从 (1, 1) 开始构建一条长蛇状路径，并通过选择延伸的距离和分支的方式来控制颜色平衡。 

基本技巧是首先构建一条长的交替路径，这自然会为我们提供几乎相同数量的白色和黑色单元，根据起始颜色和长度奇偶性最多相差一个。 然后，我们通过在路径附近附加长度为 2 的小绕道来调整不平衡。 长度为两倍的绕行会翻转颜色两次，并允许我们在不破坏连接的情况下增加一种颜色的数量。 

具体来说，我们从一个白细胞开始。 路径确定地交替颜色。 如果我们需要的白人多于黑人，反之亦然，超出了简单路径所能提供的范围，我们会插入“凹凸”，即现有节点的小型两步扩展，根据附着点的奇偶性在本地添加（1 个白色，1 个黑色）或偏差。 

该构造成为网格图上的受控增长过程，其中每个新单元格都与已选择的单元格相邻，确保自动保留连接性。

 ## 算法演练

 我们描述了一种直接的构建策略，可以逐个单元地构建组件。 

首先，我们检查可行性。 如果 a + b = 1，答案总是可能的，因为单个单元格是平凡连接的，我们只需选择 (1, 1)。 如果 a 或 b 之一为零，而总数大于 1，我们立即拒绝，因为棋盘网格中不能存在单色连通区域。 

接下来，我们决定起始颜色。 我们总是从 (1, 1) 开始，它是白色的。 这固定了结构并简化了奇偶推理。 

然后我们在网格内构建一条长蛇形路径。 我们向右移动直到一行的末尾，然后向下移动一步并反转方向，重复此模式。 这给出了类似哈密顿量的矩形遍历。 沿着这个遍历，我们收集单元格，直到至少有 a + b 个单元格可供选择。 由于网格足够大，我们总是有足够的空间。 

此时，我们从这次遍历中取出前 a + b 个单元格。 这会产生一个连接的类似路径的形状。 我们计算这个前缀包含多少白人和黑人。 

如果计数已经匹配 (a, b)，我们就完成了。 

否则，假设我们需要增加相对于黑色的白色计数。 我们沿着构建的路径扫描并寻找至少有一个未使用的相邻单元的黑色单元。 由于网格结构，每个内部单元格在路径之外都有额外的邻居，所以这样的地方总是存在的。 从该黑色单元格中，我们附加一个尚未使用的新的白色相邻单元格。 这会在保留连接性的同时添加一个白细胞。 

如果我们需要更多的黑色单元格，我们会对称地附加白色单元格的邻居。 

我们重复此调整，直到计数完全匹配。 每次调整都使用一个新的未使用的单元格，并且由于所需的总大小受 a + b 限制，因此我们永远不会用完 1000 x 1000 网格中的空间。 

### 为什么它有效

 该构造在每一步都维护一个连接的组件，因为每个新单元都通过共享边连接到现有的选定单元。 初始路径保证基础结构的连通性。 每个校正步骤仅通过添加叶节点进行修改，因此无需重构即可保留连接性。 

计数的正确性源自以下不变量：每次操作都将其中一种颜色计数精确地改变 +1，同时保持另一种颜色计数不变。 由于我们从路径前缀派生的已知（初始白色、黑色）对开始，并且每一步都朝着目标移动，因此我们最终必须到达（a，b），而不会在错误的方向上超调。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def color(x, y):
    return (x + y) & 1  # 0 white, 1 black

def solve():
    t = int(input())
    for _ in range(t):
        a, b = map(int, input().split())

        if a + b == 1:
            print("YES")
            print(1, 1)
            continue

        if a == 0 or b == 0:
            print("NO")
            continue

        # build a simple snake path
        cells = []
        n = 1000

        x = 1
        y = 1
        dir_right = True

        while len(cells) < a + b:
            cells.append((x, y))
            if dir_right:
                if y < n:
                    y += 1
                else:
                    x += 1
                    dir_right = False
            else:
                if y > 1:
                    y -= 1
                else:
                    x += 1
                    dir_right = True

        # count colors
        w = b0 = 0
        for i in range(a + b):
            if color(*cells[i]) == 0:
                w += 1
            else:
                b0 += 1

        # we now adjust by local expansions if needed
        used = set(cells[:a + b])
        res = cells[:a + b]

        def add_extra(desired_white):
            nonlocal w, b0, res, used
            for i in range(len(res)):
                x, y = res[i]
                for dx, dy in [(1, 0), (-1, 0), (0, 1), (0, -1)]:
                    nx, ny = x + dx, y + dy
                    if 1 <= nx <= 1000 and 1 <= ny <= 1000 and (nx, ny) not in used:
                        used.add((nx, ny))
                        res.append((nx, ny))
                        if color(nx, ny) == 0:
                            w += 1
                        else:
                            b0 += 1
                        return

        # fix imbalance greedily
        while w != a or b0 != b:
            if w < a:
                add_extra(True)
            else:
                add_extra(False)

        print("YES")
        for x, y in res:
            print(x, y)

if __name__ == "__main__":
    solve()
```该代码首先处理一些微不足道的不可能的事情：单个单元格的情况始终有效，而任何仅使用一种颜色但多个单元格的请求都会立即被拒绝。 

蛇形结构被实现为逐行之字形，确保我们始终保持在边界内并产生长连接的遍历。 前 a + b 单元格被视为基本组件。 

然后我们使用坐标奇偶校验来计算颜色分布。 之后，我们维护一组已使用的单元格，以确保在添加调整时不会重复使用坐标。 

调整功能扫描当前结构并附加相邻的未使用单元，保证连接性。 循环继续，直到计数与目标完全匹配。 

## 工作示例

 考虑 a = 5 且 b = 4 的情况。我们从 (1, 1) 开始并构建一条蛇形路径：

 | 步骤| 添加单元格 | 白色计数| 黑色计数|
 | ---| ---| ---| ---|
 | 1 | (1,1) | 1 | 0 |
 | 2 | (1,2) | 1 | 1 |
 | 3 | (1,3) | 2 | 1 |
 | 4 | (1,4) | 2 | 2 |
 | 5 | (1,5) | 3 | 2 |
 | 6 | (2,5) | 3 | 3 |
 | 7 | (2,4) | 4 | 3 |
 | 8 | (2,3) | 4 | 4 |
 | 9 | (2,2) | 5 | 4 |

 此时我们已经匹配(5, 4)，所以不需要调整。 施工立即停止。 

现在考虑一个倾斜的情况 a = 3, b = 1。朴素的前缀可能会给出 (2, 2)。 我们检测多余的黑色，并从结构中的任何有效白色单元附加一个额外的白色邻居，例如，如果不允许使用，则从 (1, 2) 延伸到 (2, 2)，因此我们选择一个未使用的相邻边界单元。 该过程一直持续到计数变为 (3, 1)，而连接性保持不变，因为每个新单元都由一个边缘连接。 

这些示例表明基本路径提供了近乎平衡的结构，并且小的本地附件可以纠正任何不匹配。

 ## 边缘情况

 临界边缘情况是其中一个计数为零且总数超过 1 的情况。 该算法会立即拒绝这些，因为任何单色选择都无法连接到棋盘网格中。 例如，输入 (0, 3) 必须输出 NO，因为黑色单元永远不会相互接触。 

另一个边缘情况是单单元输入 (1, 0) 或 (0, 1)。 这是有效的，并且必须使用任何单个坐标输出 YES，并且算法在任何构造之前显式处理它。 

最后的边缘情况是初始蛇前缀已经稍微超出一种颜色。 在这种情况下，调整阶段确保我们只添加单元格而不删除它们，因此在任何平衡开始之前仔细选择完全等于 a + b 的前缀长度可以避免过冲。
