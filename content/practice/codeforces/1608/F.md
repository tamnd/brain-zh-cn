 ## 解决方案
 ## 问题理解

 我们从左到右逐步构建一个数组，在每个位置之后我们查看到目前为止构建的前缀。 从该前缀我们计算它的 MEX，它是未出现在前缀中的最小非负整数。 除了这个不断演变的数组之外，我们还得到了一个目标序列。 每一步，当前前缀的MEX最多允许偏离对应的目标值`k`。 任务是计算可以构造多少个在每个前缀处满足此条件的完整数组。 

关键的困难是 MEX 不是本地统计数据。 添加值可以增加 MEX 或保持不变，具体取决于它是否填补了缺失的空白。 这意味着系统的状态不仅仅是当前的 MEX，还包括来自`0`向上已经在前缀中被“激活”。 

约束很严格：`n`最多 2000 并且`k`最多为 50。这排除了对数组或子集的任何指数枚举。 跟踪所用数字的任意子集的朴素状态表示也是不可能的，因为这意味着大约为`2^n`行为。 唯一的前进方法是将状态压缩为仅依赖于当前 MEX 范围的东西，并利用以下事实：`k`限制 MEX 可以被迫远离目标的距离。 

当目标`b_i`为负数或大于`n`。 由于 MEX 始终处于`[0, n]`，这些值充当软约束：例如，如果`b_i = -2`，条件变为`MEX >= -2 - k`，这始终是正确的，因此只有上限很重要。 同样，非常大`b_i`值仅强加一个下限。 粗心的实现没有将这些约束限制在`[0, n]`会过度限制或限制转换并产生错误的计数。 

另一个棘手的情况是 MEX 上涨时。 例如，如果在某个前缀我们有所有数字`0..4`目前，墨西哥`5`。 添加另一个`5`不改变MEX，但添加缺失的`3`或者`1`也可能是不可能的，因为重复项不会影响 MEX。 许多天真的 DP 公式错误地假设每个新元素单调增加覆盖范围，这是错误的。 

## 方法

 暴力方法会尝试构造所有数组`a`并逐个前缀检查 MEX 约束是否成立。 对于每个位置，我们将通过前缀从头开始重新计算 MEX，这会花费`O(n)`每一步，并且有`n^n`总共数组。 即使通过约束进行修剪也没有足够的帮助，因为早期的前缀在 MEX 稳定之前允许有很多选择。 这远远超出了任何可行的计算。 

关键的观察结果是，MEX 仅取决于前缀中哪些小数字已完全“完成”。 一旦一个号码`x`至少出现一次，它有助于潜在地增加 MEX。 重要的不是完整的集合结构，而是第一个缺失的整数。 

我们追踪当前的 MEX`m`。 前缀包含所有数字`0..m-1`， 和`m`缺席。 任何新元素要么填充下面缺失的数字`m`，这会增加 MEX，或者是不相关的噪声（大于的值`m`）。 这种结构意味着转换取决于我们是否引入缺失值。 

我们将其转化为头寸和可能的 MEX 值的 DP。 约束条件`|MEX - b_i| <= k`将每一步的有效 MEX 值限制在一个小窗口内`b_i`，所以我们只在一定范围内维持 DP`O(k)`围绕每个可能的 MEX。 然后，转换来自于保持相同的 MEX 或通过填充当前缺失的数字来增加它。 

为了有效地计算我们可以“不改变 MEX”与“增加 M​​EX”的方式，我们保持组合选择：在每一步，选择一个大于当前 MEX 的值相当于`n - m`选项，而选择一个缺失的数字来完成 MEX 恰好是一个特定值。 

这将问题简化为具有线性转换的 MEX 状态上的受控 DP。

 ## 算法演练

 我们定义`dp[i][m]`作为构建第一个的方法的数量`i`使得前缀的 MEX 恰好是`m`。 自从`m`总是介于`0`和`n`，但受限于`b_i`，我们只考虑其中的状态`m`在于`[b_i - k, b_i + k]`。 

1. 初始化`dp[0][0] = 1`。 一开始，不存在任何元素，MEX 是`0`因为`0`立即失踪。 
2. 对于每个位置`i`从`1`到`n`，我们建立一个新的DP表`ndp`。 
3. 对于每个可能的 MEX 值`m`在步骤约束下有效`i`，我们考虑从先前状态的两种类型的转换。 
4. 首先，我们考虑保持MEX不变。 当我们添加一个不能填充缺失整数的值时，就会发生这种情况`m`。 有`m`选择已经完全“不活动”的值（大于或等于当前 MEX 不会降低正确性），以及`(n - m)`选择不影响 MEX 的值。 关键思想是任何大于`m`MEX 保持不变。 
5. 其次，我们考虑增加MEX。 移动自`m`到`m+1`，我们必须将值`m`第一次出现在前缀中。 这正是值的一种选择，但仅当先前的前缀具有 MEX 时才有效`m`现在我们插入`m`。 
6. 我们对这些贡献求和并存储结果模`998244353`。 
7. 处理完所有位置后，我们将所有位置相加`dp[n][m]`在哪里`m`在步骤中有效`n`。 

### 为什么它有效

 不变的是每一步，`dp[i][m]`精确计算构造前缀的方法的数量，该前缀的当前数字集使得`m`最小的缺失整数。 任何有效的前缀都必须恰好落入其中一种状态，因为 MEX 是由前缀唯一确定的。 转换保留了正确性，因为每个数组扩展要么引入缺失的 MEX 元素（强制确定性增加），要么避免它（保持 MEX 不变）。 没有其他操作可以影响 MEX 边界，因此所有有效数组都只计算一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    b = list(map(int, input().split()))

    # dp[m] = number of ways with current MEX = m
    dp = [0] * (n + 2)
    dp[0] = 1

    for i in range(1, n + 1):
        ndp = [0] * (n + 2)
        bi = b[i - 1]

        # valid mex range at step i
        L = max(0, bi - k)
        R = min(n, bi + k)

        for m in range(L, R + 1):
            val = dp[m]
            if not val:
                continue

            # case 1: choose value > m or from "irrelevant pool"
            # there are (n - m) choices that do not introduce m
            ndp[m] = (ndp[m] + val * (n - m)) % MOD

            # case 2: try to introduce m and increase mex
            if m + 1 <= n:
                ndp[m + 1] = (ndp[m + 1] + val) % MOD

        dp = ndp

    # sum all valid final mex states
    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```该实现维护单个 DP 数组并针对每个位置对其进行适当更新。 关键的细节是限制过渡`[b_i - k, b_i + k]`，它修剪不可能的 MEX 状态并保持复杂度线性`n · k`。 

乘法`(n - m)`反映任何严格大于当前 MEX 的值都不会影响缺失前缀结构。 第二个转换通过放置丢失的整数来编码推进 MEX 的独特方式。 

一个微妙的实现问题是索引：MEX 可以达到`n`，因此数组必须安全地容纳`n + 1`。 另一个是确保负面`b_i - k`被钳位为零，因为 MEX 不能为负。

 ## 边缘情况

 当出现临界边缘情况时`b_i - k < 0`。 在这种情况下，有效的 MEX 窗口必须钳位为零。 如果不这样做，DP 可能会尝试访问负 MEX 状态，从而有效地丢弃有效配置。 例如，与`b_i = 0, k = 5`，正确的解释是 MEX 始终允许为零或大于 5，但绝不能为负数。 

另一个边缘情况出现在`m = n`，其中尝试增加 MEX 的转换将超出界限。 DP必须明确保护`m + 1 <= n`，因为 MEX 不能超过`n`。 如果没有这个，数组的索引将超出范围或错误地计算无效状态。 

最后，当`b_i`很大，比如`b_i = n + k`，约束窗口实际上变成`[n, n]`，迫使 MEX`n`。 在这种情况下，每个前缀必须包含所有数字`0..n-1`，并且 DP 崩溃为确定性组合过程。 该实现自然地处理了这个问题，因为只有`m = n`在 DP 窗口中存活。
