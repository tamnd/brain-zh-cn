 ## 解决方案
 ## 问题理解

 该问题给出两个非负整数A和B。我们必须在0到B的区间中选择一个整数b，并最大化A XOR b的值。 输出是可以获得的最大异或值。 输入值可以大到 10^18，因此该解决方案必须适用于包含大约 60 位的数字。 

尝试所有可能的 b 的解决方案立即是不可能的。 如果 B 是 10^18，则大约有 100 万个候选者，远远超出了正常竞赛限制内可以检查的数量。 即使对每个值进行非常优化的恒定时间检查也需要太多操作。 由于相关位数仅为 60 左右，因此预期的解决方案应取决于二进制表示而不是数值范围的大小。 

棘手的情况来自于 b 是有界的，而不是固定的。 简单地翻转 A 的每一位的贪婪方法通常会创建一个大于 B 的数字。 

例如：```
Input:
5 4

Output:
7
```这里 A 是二进制的 101，B 是 100。选择 b = 2 得到 101 XOR 010 = 111，即 7。粗心的解决方案可能会选择 b = 0，因为 B 的最高位等于 A 的最高位，忽略了较小的前缀允许以后有更多的自由。 

另一个边缘情况是 B 本身是最佳选择。```
Input:
7 32

Output:
39
```最好的 b 是 32，因为 7 XOR 32 = 39。仅考虑与 A 具有相同位长度的值的方法可能会错过有效答案。 

最后一个重要的情况是 B = 0。```
Input:
10 0

Output:
10
```只有一个可能的选择，b = 0。任何假设总是可以降低 B 的一位以获得灵活性的算法在这里都会失败。 

## 方法

 直接的方法是测试从 0 到 B 的每个可能的 b，计算 A XOR b，并保留最大值。 这是正确的，因为考虑了每个允许的值。 最坏的情况是 O(B) 操作，变成 O(10^18) 并且不可用。 

关键的观察是 XOR 比较的工作原理与普通的二进制比较完全相同。 为了最大化最终数字，我们可以做出决定的最重要的位首先重要。 如果我们可以使结果的某一位等于 1 而不使 b 超过 B，我们应该立即这样做，因为在高位不同后，每个低位都变得无关紧要。 

从最高有效位到最低有效位处理位。 在匹配B的前缀时，我们有两种选择。 我们可以保持 b 的当前位等于 B 的位，这意味着前缀保持相等并且未来的选择受到限制。 或者，如果B在这个位置有一个1，我们可以在b中放置一个0，使b的前缀小于B的前缀。 一旦前缀变小，b 的每个剩余位都可以自由选择，因此我们只需选择与 A 最大化异或的位即可。 

这将问题简化为仅检查大约 60 位位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(B) | O(1) | O(1) | 太慢了|
 | 最佳| O(log B) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取 A 和 B，并从最高位到第 0 位检查它们的位。只需要大约 60 位，因为数字最多为 10^18。 
2. 维护所选数字b的前缀是否已经小于B的前缀。如果更小，则剩余位不受限制，因为任何延续仍将产生低于B的值。 
3. 如果前缀已经较小，则将 b 的每个剩余位设置为 A 的相反位。 这使得每个剩余的 XOR 位都等于 1。 
4. 如果前缀等于B，则比较B的当前位。如果是0，则b在该位置也必须使用0。 如果是1，则考虑选择在b中放入0。 这使得 b 小于 B，并为所有后面的位提供了自由，因此答案可以采用最好的后缀。 
5. 跟踪两种可能状态获得的最大答案。 该实现可以通过直接构造最佳异或值来避免存储实际的 b 值。 

为什么它有效：两个可能答案不同的最高位决定哪个答案更大。 在每一位上，算法都会选择是否可以在不违反 b <= B 的情况下在答案中创建 1。如果可以使前缀更小，则可以独立优化所有较低位。 如果不可能，则强制使用当前位。 因此，每个决策都保留了最大可实现的前缀，并且在处理所有位之后，完整的答案是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    A, B = map(int, input().split())

    ans = 0
    smaller = False

    for i in range(60, -1, -1):
        abit = (A >> i) & 1
        bbit = (B >> i) & 1

        if smaller:
            ans |= (1 << i)
        else:
            if bbit == 0:
                if abit == 1:
                    ans |= (1 << i)
            else:
                if abit == 0:
                    ans |= (1 << i)
                smaller = True

    print(ans)

if __name__ == "__main__":
    solve()
```循环从高到低处理位，因为较高位决定最终 XOR 值的数字顺序。 变量`smaller`记录构造的 b 前缀是否已经低于 B。一旦发生这种情况，上限就不再限制未来的位。 

什么时候`B`有一个零位，当前缀相等时，b 的相应位被强制为零。 XOR 位则完全由 A 决定。`B`有一个 1 位，选择 b 的位为零会创建一个较小的前缀，并允许所有未来的 XOR 位变为 1。 这就是为什么代码在处理这样的位置后立即将状态标记为较小的原因。 

Python 整数不会溢出，因此 60 位操作是安全的。 该循环包括位 60 以覆盖最大可能值 10^18。

 ## 边缘情况

 对于`A = 5`和`B = 4`，B的第一位给出了一个选择。 将 b 的最高位设为 0 使得 b 小于 B，因此可以选择所有较低位来对抗 A。算法得出相同的决策并产生 7。 

对于`A = 7`和`B = 32`，B的第一位允许构造的数立即变小。 在那之后，剩余的每个答案位都可以变成 1，产生 39。 

对于`A = 10`和`B = 0`，b 的每一位都被强制为零，因为不可能有更小的前缀。 答案正是 A XOR 0，即 10。
