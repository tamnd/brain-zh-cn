 ## 解决方案
 ## 问题理解

 我们有一个固定的排列`p`尺寸的`n`。 思考每个位置`i`作为一个具有两个独立标签的点：它的位置索引和它的值`p_i`。 

我们必须构建另一个排列`q`这样对于每个索引`i`，我们可以计算有多少个索引`j > i`同时满足两个条件：`p_j > p_i`和`q_j > q_i`。 该计数必须与给定的目标值匹配`d_i`。 

所以每一对`(i, j)`有助于`d_i`仅当`j`是在右边`i`和`j`大于`i`在两种排列中`p`和`q`。 任务是分配`q`以便这些优势关系准确地产生所需的计数。 

主要的困难在于`q`每个索引不是独立的。 任何分配都会改变全局比较，每对索引都可能影响两个不同的索引`d`值不对称，具体取决于顺序约束。 

约束允许总计`n`所有测试中最多 5000，因此`O(n^2 log n)`甚至`O(n^2)`每次测试解决方案都是可接受的。 在最坏的情况下，任何立方体都已经存在风险。 

一个关键的结构边缘情况立即从定义中出现。 如果一个索引`i`没有有效的`j > i`和`p_j > p_i`，那么它的`d_i`必须为零。 如果它不为零，则答案是不可能的。 这是因为优势要求两个坐标都严格增加，并且如果`p_i`已经是后缀最大值，未来的索引不能超过它`p`。 

另一个微妙的情况是，可行性取决于每个职位存在多少潜在的主导候选人。 即使存在候选者，我们也必须能够将它们一致地分布在所有候选者中。`d_i`不违反排列约束的值`q`。 

## 方法

 蛮力策略会尝试所有排列`q`并计算每个索引的优势计数。 对于每位候选人`q`，我们将扫描所有对`(i, j)`并验证诱导计数是否匹配`d`。 这需要花费`O(n^2)`每个排列，并且有`n!`排列，即使对于`n = 10`。 

即使是稍微聪明一点的蛮力也可以构建`q`增量仍然面临组合爆炸，因为每个位置都以非局部方式改变未来的支配关系。 

关键的见解是重新解释条件`p_j > p_i and j > i`作为由以下引起的固定偏序`p`和索引顺序。 我们唯一拥有的自由是由`q`。 一次`p`是固定的，每个索引`i`有一批潜在的继任者可以主导它。 其中，我们只关心他们是否`q`值大于`q_i`。 

这将问题转化为构建排列`q`使得每个位置`i`正好有`d_i`一组已知的有效后继者中的“较大 q 后继者”。 这相当于在尊重可行性约束的同时分配排名，其行为类似于对排序位置的贪婪分配。 

正确的方法是按降序处理索引`p`并分配`q`以升序排列，同时维持一个跟踪剩余多少可用“未来有效”职位的结构。 每次我们分配一个值时，我们都会确保它消耗正确数量的未来候选者以满足剩余的需求`d`。 

我们将问题简化为对按索引排序的动态集的贪婪构造，其中我们总是选择所需的位置`d_i`与剩余后缀中的可用容量相匹配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!·n²) | O(n!·n²) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们建造`q`从左到右，但使用跟踪后缀中剩余容量的结构来保持可行性。 

1. 对索引进行降序排序`p_i`。 这确保了当我们处理索引时，所有可能的`j > i`和`p_j > p_i`尚未分配更高优先级的决策。 此排序使依赖方向与处理顺序保持一致。 
2. 维护已经有资格被视为未来主导者的活跃指数的数据结构。 每个活跃指数对应一个潜在的`j`对于早期处理的索引。 
3. 对于每个索引`i`在减少中`p_i`，我们决定它的位置`q`相对于当前活动的元素，以便准确地`d_i`活动元素放置在它之后`q`。 
4. 为了实现这一点，我们维持一个 Fenwick 树或持仓平衡结构`q`支持：

 - 插入新索引，
 - 计算当前在给定位置之后放置了多少个活动元素，
 - 找到给定“反转等级”发生的位置。 
5. 我们分配`q`贪婪地值：我们按顺序处理索引并将它们放置在一个结构中，其中右侧较大元素的数量为`q`比赛`d_i`。 
6. 如果在任何一步`d_i`如果超过了可用的未来兼容元素的数量，我们立即得出不可能的结论。 
7. 否则，我们提取有效的排列`q`从构建的排序。 

关键操作是每次插入都会在其右侧强制执行固定数量的较大元素，与所需的优势计数完全匹配。 

### 为什么它有效

 目前我们正在处理一个索引`i`，所有可能在两个维度上占据主导地位的指数都已在主动结构中得到考虑。 选择放置位置`i`在不断演变的排列中`q`准确地确定有多少活动元素最终位于其右侧。 因为统治力只取决于`j > i`,`p_j > p_i`， 和`q_j > q_i`，并且我们以递减的方式处理`p`，有效的集合`j`正是当前的活动集。 因此令人满意`d_i`本地保证全局正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def kth(self, k):
        cur = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = cur + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                cur = nxt
            bitmask >>= 1
        return cur + 1

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    d = list(map(int, input().split()))

    order = sorted(range(n), key=lambda i: -p[i])

    bit = Fenwick(n)
    used = 0

    q = [0] * n

    for i in order:
        if d[i] > used:
            print(-1)
            return

        pos = used - d[i] + 1
        idx = bit.kth(pos)

        q[i] = idx
        bit.add(idx, 1)
        used += 1

    print(*q)

t = int(input())
for _ in range(t):
    solve()
```芬威克树维护了哪些位置`q`已经被占用了。 变量`used`跟踪到目前为止已放置的元素数量。 对于每个索引`i`，算法确定必须插入的位置，以便准确地`d[i]`已放置的元素在最终排序中最终位于其右侧`q`。 

这`kth`查询找到实际位置`q`这对应于所需的反转结构。 这将抽象要求“准确地`d_i`在我之后更大的元素”转化为具体的位置选择问题。

 按递减顺序排列`p`确保每次我们分配位置时，所有有效的未来统治者都已经在系统中。

 考虑一个小案例：

 输入：```

p = [3, 1, 4, 2]

```我们按递减排序`p`：指数`[2, 0, 3, 1]`。 

| 步骤| 我| p[i] | p[i] d[i] | 二手 | pos = 使用-d+1 | 选择索引 | q 状态 |

 这会产生一个有效的排列，其中每个索引都准确地获得其所需数量的主导后继者。

 ## 边缘情况

 当索引是后缀最大值时，就会出现临界边缘情况`p`。 例如：```
p = [1, 3, 2]
d = [1, 0, 0]
```指数`2`有`p_2 = 3`，并且没有`j > 2`存在较大的`p`。 因此它永远不能被任何未来指数所支配。 如果`d_2 > 0`，算法立即拒绝。 

贪心构造也自然地处理了这个问题，因为在处理时`p=3`，没有活跃的候选人可以证明积极的`d`。 任何分配非零要求的尝试都会违反条件`d[i] ≤ used`，触发失败。 

这确保了不可能的配置在破坏部分排列构造之前被过滤掉。
