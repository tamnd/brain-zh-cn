[CF 2217B - 翻转位（简单版）](https://codeforces.com/problemset/problem/2217/B)

 **评分：** 1000
 **标签：** 贪心，实现
 **求解时间：** 1m 42s
 **已验证：** 否

 ## 解决方案
 ## 问题理解

 我们给定一个长度的二进制数组$n$和一个特殊索引$p_1$（自从$k=1$）。 该特殊索引处的元素具有值$x$，我们的目标是使整个数组等于$x$。 为此，我们可以对包含特殊索引的连续子数组执行任意数量的翻转操作。 翻转会反转所选范围内的每一位。 

实际上，问题是问：包含所需特殊索引的连续子数组翻转的最小数量是多少，以便所有元素都与该索引处的值匹配？ 

因为$n$可以达到$2 \cdot 10^5$并且最多可以有$10^4$测试用例，复杂的解决方案$O(n^2)$每个测试用例都会太慢。 我们需要一个相对于数组大小的线性解。 

不明显的边缘情况包括：已经全部等于的数组$x$，或者当$x$为0且所有1连续出现在特殊索引的一侧。 不加区别地翻转的粗心方法可能会执行不必​​要的操作。 

## 方法

 暴力方法会考虑包含特殊索引的所有可能范围，翻转它们，并递归地尝试最小化翻转。 这是正确的，但不可行。 对于单个特殊索引，暴力可能会尝试包含该索引的每个子数组，但大致有$O(n^2)$这样的范围。 这很快就超出了时间限制。 

关键的观察是每个连续的元素段不等于$x$并且在同一侧的特殊索引可以通过一次翻转来固定。 跨越多个此类段的翻转没有用，因为它们还会反转已经正确的元素。 因此，最小翻转次数是特殊索引两侧连续“错误”段的数量。 

为了有效地实现这一点，我们扫描数组到特殊索引的左侧和右侧，计算不等于的连续值段$x$，并对这些计数求和。 这直接给出了最少的操作$O(n)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 确定价值$x$在特殊索引处。 
2. 将翻转计数器初始化为零。 
3. 从最近到最远扫描特殊索引左侧的数组。 每当连续的元素块不同于$x$，将翻转计数器加一并跳过该块。 
4. 使用相同的过程扫描特殊索引右侧的数组。 每个连续块不同于$x$算作一次翻转。 
5. 返回翻转的总数。 

为什么有效：每次翻转都必须包含特殊索引，因此我们无法独立翻转另一侧的元素。 每侧连续的错误值序列可以通过每个序列一次翻转来修复，从而保证最少的操作次数。 任何拆分或组合翻转的尝试都会要么留下一些错误的位不变，要么执行冗余的翻转。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        p = list(map(int, input().split()))
        x = a[p[0]-1]
        
        flips = 0
        # Left of special index
        i = p[0]-2
        while i >= 0:
            if a[i] != x:
                flips += 1
                while i >= 0 and a[i] != x:
                    i -= 1
            else:
                i -= 1
        # Right of special index
        i = p[0]
        while i < n:
            if a[i] != x:
                flips += 1
                while i < n and a[i] != x:
                    i += 1
            else:
                i += 1
        print(flips)

if __name__ == "__main__":
    solve()
```该解决方案首先读取测试用例的数量并对其进行迭代。 对于每个测试用例，它提取数组和特殊索引，调整基于 0 的索引，并从特殊索引左右扫描以计算错误值的连续序列。 内`while`循环会跳过整个段，以确保每次翻转都被精确计数一次。

 ## 边缘情况

 单元素数组：特殊索引是唯一的元素，已经等于其自身。 算法正确返回 0。 

所有元素都等于特殊值的数组：左右扫描立即终止，而不增加翻转。 

围绕特殊索引交替序列：内部`while`循环确保每个连续段只计算一次，从而防止过度计数。 

包含特殊索引本身的段：由于我们只从特殊索引左右扫描，因此不会造成重复计数。 

该算法通过在索引 0 和 n-1 处停止来正确处理边界。 

这证实了琐碎和棘手的配置的正确性。
