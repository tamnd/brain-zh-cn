 ## 解决方案
 ## 问题理解

 我们有`n`湖里的鱼。 每天，均匀地随机选择一对无序的当前存活的鱼。 当鱼`i`遇见鱼`j`， 鱼`i`吃鱼`j`有概率`a[i][j]`，和鱼`j`吃鱼`i`有概率`a[j][i] = 1 - a[i][j]`。 

这个过程一直持续到只剩下一条鱼还活着。 对于每条鱼，我们必须计算它成为最终幸存者的概率。 

输入是概率矩阵。 入口`a[i][j]`告诉我们鱼的机会`i`打败鱼`j`在直接的相遇中。 该矩阵一般是不对称的，但每一对都满足：```
a[i][j] + a[j][i] = 1
```约束条件`n ≤ 18`完全塑造解决方案。 所有战斗命令的暴力模拟会立即爆炸，因为可能的消除序列的数量大致为：```
n * (n - 1) * (n - 2) * ...
```这就是阶乘增长。 即使是为了`n = 18`，这是一个天文数字。 

数量`2^18 = 262144`对于子集动态规划来说足够小。 每当`n`大约是 20，位掩码 DP 通常是首先要研究的。 每个活鱼子集的状态都变得现实。 

有一些容易被忽视的案例打破了不正确的公式。 

考虑这个输入：```
2
0 1
0 0
```鱼`0`总是打败鱼`1`。 正确答案是：```
1.000000 0.000000
```如果不小心实现，在两条鱼之间对称分配概率，就会错误地产生`0.5 0.5`。 

另一个微妙的情况是当多个路径通向同一个活动集时。```
3
0 0.5 0.5
0.5 0 0.5
0.5 0.5 0
```所有的鱼都是对称的，所以每个答案都必须准确`1/3`。 如果 DP 忘记累积所有前任状态的贡献，则概率之和将停止为`1`。 

更危险的错误出现在转移概率本身。 假设活鱼是`{0,1,2}`。 确切地说有：```
C(3,2) = 3
```可能相遇的对。 如果有鱼`0`死于鱼`1`，转移概率必须包括除以`3`。 忘记这种归一化会使总概率超过`1`。 

## 方法

 蛮力的想法很简单。 在每一步中，选择每对可能的活鱼，根据两种可能的战斗结果进行分支，并递归地继续，直到剩下一条鱼。 

这是有效的，因为该过程是无记忆的。 未来仅取决于当前的活动集。 如果我们递归地枚举每个可能的消除链并沿路径乘以概率，我们最终会得到准确的答案。 

问题是递归树中的状态数。 一开始有：```
C(n,2)
```可能的会议。 排除一次后有：```
C(n-1,2)
```等等。 

战斗序列的总数大致以阶乘时间的方式增长。 为了`n = 18`，这是完全不可行的。 

关键的观察结果是许多递归分支到达活鱼的同一子集。 

例如，假设活鱼变成`{0,2,5}`。 早期淘汰的确切顺序产生这盘并不重要。 从那时起，未来的概率是相同的。 

这意味着状态可以压缩为：```
mask = set of alive fish
```这立即表明了 DP 子集。 

定义：```
dp[mask] = probability that exactly the fish in mask are alive
```我们从全套开始，其中每条鱼都有概率活着`1`。 

来自一个州`mask`，我们从所有活鱼中统一选择一对。 一条鱼死了，产生了一个更小的面具。 

由于每次转换恰好删除一条鱼，因此状态图是非循环的。 我们可以加工从大到小的口罩。 

子集的数量是`2^n`，对于每个子集，我们可以检查成对的鱼。 和`n ≤ 18`，这变得可行。

 | --- | --- | --- | --- |
 | 蛮力 | 指数阶乘增长 | 指数| 太慢了 |
 | 最佳位掩码 DP | O(2^n·n²) | O(2^n·n²) | O(2^n) | O(2^n) | 已接受 |

 ## 算法演练

 1. 将每个活动集表示为位掩码。 

少量`i`是`1`如果鱼`i`还活着。 和`n ≤ 18`，整个状态可以轻松地容纳在一个整数内。 
2. 定义DP状态。 

让：```
dp[mask]
```是当前活着的鱼正是其中那些鱼的概率`mask`。 
3. 初始化启动状态。 

最初每条鱼都是活的，所以：```
full = (1 << n) - 1
dp[full] = 1
```4. 将掩模从较大的子集处理到较小的子集。 

每次转换都会删除一条鱼，因此概率总是流向位数较少的掩码。 
5. 对于当前掩码，计算有多少条鱼还活着。 

认为`k`鱼是活的。 那么可能的会议对的数量为：$\frac{k(k-1)}{2}$每对都是统一选择的。 
6. 迭代每个有序对`(i, j)`活鱼在哪里`i != j`。 

如果有鱼`i`吃鱼`j`，下一个状态变为：```
next_mask = mask ^ (1 << j)
```因为鱼`j`死了。 
7. 添加转移概率。 

概率贡献为：$dp[mask] \cdot \frac{a_{ij}}{\binom{k}{2}}$我们除以可能的会议数量，因为每个无序对都有相同的可能性被选择。 
8. 继续，直到处理完所有掩模。 

最终，每个单例掩码都会从所有更大的状态接收到其总概率。 
9. 提取答案。 

鱼`i`当最终状态为：```
mask = (1 << i)
```为什么它有效：

 DP 不变量为：```
dp[mask] = probability that the process ever reaches exactly this alive set
```初始状态是正确的，因为该过程从所有鱼都活着开始。 每个转换都会模拟该过程中的一个合法事件：统一选择一对会议，然后应用战斗概率。 由于每个可能的下一个事件仅被考虑一次，因此概率质量在状态之间正确转移。 因为转换只会删除鱼，所以不存在循环，并且每个状态在进一步使用其值之前都会累积所有有效前驱状态的贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [list(map(float, input().split())) for _ in range(n)]

    size = 1 << n
    dp = [0.0] * size

    full = size - 1
    dp[full] = 1.0

    for mask in range(full, 0, -1):
        alive = []

        for i in range(n):
            if mask & (1 << i):
                alive.append(i)

        k = len(alive)

        if k <= 1:
            continue

        pairs = k * (k - 1) / 2.0

        for i in alive:
            for j in alive:
                if i == j:
                    continue

                next_mask = mask ^ (1 << j)
                dp[next_mask] += dp[mask] * a[i][j] / pairs

    ans = []

    for i in range(n):
        ans.append(f"{dp[1 << i]:.6f}")

    print(*ans)

solve()
```DP 数组存储活鱼每个子集的概率。 完整的掩码包含最初所有活着的鱼，所以它的概率开始于`1`。 

外循环通过掩码向下迭代。 这个顺序很重要，因为转换总是删除一条鱼。 较小的掩码永远不会返回到较大的掩码中。 

对于每个面具，我们首先收集活鱼。 这简化了对迭代并避免了重复的位检查。 

变量`pairs`存储活鱼之间可能发生的无序会议的数量。 这是许多错误实现所忽略的标准化因素。 如果不除以该值，概率将无法正确求和。 

嵌套循环迭代有序对`(i, j)`。 这是故意的。 每个有序对对应一个特定的消除事件：鱼`i`杀死鱼`j`。 

过渡：```
next_mask = mask ^ (1 << j)
```去除鱼`j`来自活动集。 

浮点精度就足够了，因为答案只需要`1e-6`准确性。

 ## 边缘情况

 考虑尽可能最小的输入：```
1
0
```最初的面具已经包含了一条鱼。 DP 的开头是：```
dp[1] = 1
```没有发生任何转换，因为`k <= 1`。 算法正确输出：```
1.000000
```现在考虑确定性主导：```
2
0 1
0 0
```初始状态：

 | 面膜| 活着| DP |
 | --- | --- | --- |
 | 11 | 11 {0,1} | 1 |

 只有一对。 鱼`0`打败鱼`1`有概率`1`。 

过渡：

 | 来自 | 至 | 概率 |
 | --- | --- | --- |
 | 11 | 11 01 | 1 |

 最终结果：```
1.000000 0.000000
```这验证了 DP 可以处理硬概率而没有浮点不稳定。 

最后，检查多个路径合并到同一状态的情况：```
3
0 0.5 0.5
0.5 0 0.5
0.5 0.5 0
```面具`{0,1}`可以通过鱼到达`0`杀戮`2`或鱼`1`杀戮`2`。 DP 将这两种贡献添加到同一状态值中。 

追踪：

 | 过渡 | 对面具011的贡献|
 | --- | --- |
 | 0 杀 2 | 1/6 | 1/6
 | 1 杀 2 | 1/6 | 1/6

 全部的：```
dp[011] = 1/3
```这种积累正是子集 DP 在这里发挥作用的原因。 不同的消除历史会崩溃到相同的未来状态。
