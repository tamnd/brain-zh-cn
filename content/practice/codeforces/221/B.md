 ## 解决方案
 ## 问题理解

 我们被要求计算给定正整数 _x_ 与 _x_ 至少共享一位数字的除数。 换句话说，我们检查每个整除_x_的数字_d_，并检查是否存在一个数字同时出现在_x_和_d_中。 输入是单个整数 _x_，最大可达 10 亿。 输出是一个表示有效除数计数的整数。 

给定上限$10^9$，检查直到 _x_ 的每个数字的简单方法将需要多达十亿次操作，这对于 2 秒的时间限制来说太慢了。 我们需要一种可扩展性更好的方法。 然而，除数有一个有用的属性：它们成对出现，并且最多有$O(\sqrt{x})$不同的除数对。 这一观察结果表明，即使对于最大的输入，我们也可以将搜索限制在大约 30,000 次操作。 

一个微妙的边缘情况是 _x_ 是一位数。 在这种情况下，每个除数也是一位数，因此我们必须确保比较正确处理一位数重叠。 另一种情况是当_x_有重复的数字时，或者当除数的数字少于_x_时； 我们必须比较数字集而不是假设位置对齐。 

## 方法

 最简单的方法是暴力破解：迭代从 1 到 _x_ 的每个整数，检查它是否整除 _x_，然后验证除数的任何数字是否出现在 _x_ 中。 这在逻辑上是可行的，但检查十亿以内的所有数字是不可行的。 

提高效率的关键在于除数成对出现：对于从 1 到$\sqrt{x}$，如果 _i_ 整除 _x_，则 _x / i_ 也整除 _x_。 这减少了我们必须显式检查最多的除数数量$2 \times \sqrt{x}$，在期限内是可行的。 

一旦我们有了每个除数，我们就将它的数字表示为一个集合。 我们还预先计算 _x_ 中的数字集。 检查这些集合之间的交集使我们能够快速确定除数是否与 _x_ 共享一个数字。 此方法是正确的，因为我们检查所有除数并显式检查数字条件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(x * log x) | O(x * log x) | O(log x) | 太慢了 |
 | 除数枚举 + 数字集 | O(sqrt(x) * log x) | O(sqrt(x) * log x) | O(log x) | 已接受 |

 ## 算法演练

 1. 从输入中读取整数 _x_ 并将其转换为字符串以提取其数字。 将这些数字存储在一组中以进行快速成员资格测试。 
2. 将计数器初始化为零。 这将跟踪与 _x_ 共享一个数字的除数的数量。 
3. 将 _i_ 从 1 迭代到$\lfloor \sqrt{x} \rfloor$。 对于每个 _i_，检查它是否能均匀地划分 _x_。 如果是，则 _i_ 和 _x / i_ 是约数。 
4. 对于每个除数，将其转换为字符串并形成其数字的集合。 检查该集合是否与 _x_ 的数字集相交。 如果是，则增加计数器。 
5. 如果 _i_ 和 _x / i_ 不同（即 _i_ 不是 _x_ 的平方根），则对 _x / i_ 执行相同的数字交叉检查。 这可确保考虑一对中的两个除数。 
6. 完成迭代后，打印计数器。 这是与 _x_ 至少共用一位数字的除数总数。 

为什么它有效：该算法通过检查来枚举 _x_ 的所有除数$\sqrt{x}$并利用除数对称性来避免遗漏任何内容。 使用集合进行数字比较可确保正确计算所有可能的重叠。 每个除数仅检查一次，并且所有数字比较都是准确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

x = int(input().strip())
digits_x = set(str(x))
count = 0

i = 1
while i * i <= x:
    if x % i == 0:
        # Check first divisor
        if digits_x & set(str(i)):
            count += 1
        # Check paired divisor if distinct
        paired = x // i
        if paired != i and digits_x & set(str(paired)):
            count += 1
    i += 1

print(count)
```该解决方案首先将 _x_ 转换为一组数字以进行有效比较。 该循环仅迭代到 _x_ 的平方根，确保每个除数对仅检查一次。 集合之间的交集运算检查共享数字。 当 _x_ 是完全平方数时，单独处理平方根可以避免重复计算。

 ## 边缘情况

 对于完全平方数（例如 49），将检查除数 7 和 49。 该算法正确地计算了 7 和 49 各一次，因为它仅在除数不同时进行双重检查。 对于像 1000000000 这样带有零的大数，该算法可以正确识别包含数字 1 的除数，并忽略那些只有零的除数。 单位数字输入（例如 1 或 7）会被自然处理，因为集合与自身的交集保证会成功。 这种方法可确保准确计算所有边缘情况。
