 ## 解决方案
 ## 问题理解

 我们给出了一个递归过程，该过程对以下数字的排列进行操作`1`到`n`。 

该函数的行为如下：

 对于`f(x)`，它首先递归地处理第一个`x - 1`元素，然后交换位置`x - 1`和`x`。 

如果我们打电话`f(n)`，递归最终按顺序执行这些交换：

 - 交换位置`(1, 2)`- 交换位置`(2, 3)`- 交换位置`(3, 4)`- ...
 - 交换位置`(n - 1, n)`任务不是模拟排序。 相反，我们必须构造一个初始排列，以便在执行所有这些交换后，最终的数组按升序排序。 

约束条件`n ≤ 1000`非常小。 即使是二次模拟也能轻松地满足限制。 真正的挑战是识别隐藏在递归过程中的模式。 

一个常见的错误是假设答案必须以某种方式类似于反转数组。 例如，与`n = 4`，从：```
4 3 2 1
```掉期产生：```
3 4 2 1
3 2 4 1
3 2 1 4
```这是没有排序的。 

另一个容易犯的错误是误解了交换的顺序。 递归不会重复地使元素冒泡。 每个相邻对从左到右恰好交换一次。 

为了`n = 3`，交换是：```
swap(1,2)
swap(2,3)
```如果初始数组是：```
2 1 3
```然后交换后：```
1 2 3
1 3 2
```结果不正确。 不跟踪实际交换顺序的粗心实现很​​容易产生此类无效结构。 

最小的边缘情况是`n = 1`。 根本没有发生交换，所以唯一有效的答案是：```
1
```任何依赖于移位元素而不单独处理此问题的解决方案都可能意外地产生空数组或无效索引。 

## 方法

 最直接的蛮力想法是尝试来自`1`到`n`，模拟递归过程，并检查最终数组是否已排序。 

这是可行的，因为递归函数是确定性的。 一旦起始排列确定，所有交换后的结果数组就被唯一确定。 

对于每个排列，我们执行`n - 1`交换，因此检查一位候选人的成本`O(n)`。 问题是排列的数量。 有`n!`的可能性。 

即使是为了`n = 10`，这已经变成：```
10! = 3,628,800
```快速尝试所有排列变得不可能。 

关键的观察结果是递归函数执行非常简单的转换。 除了第一个元素移动到末尾之外，每​​个元素都会向左移动一个位置。 

例如：```
[a1, a2, a3, a4]
```交换后变为：```
[a2, a3, a4, a1]
```我们可以直接验证这一点：```
swap(1,2): [a2, a1, a3, a4]
swap(2,3): [a2, a3, a1, a4]
swap(3,4): [a2, a3, a4, a1]
```现在问题就变得简单了。 

我们希望最终的数组是：```
1 2 3 ... n
```由于该操作将数组向左旋转一位，因此初始排列必须是已排序数组向右旋转一位：```
n 1 2 3 ... n-1
```递归交换后：```
1 2 3 ... n
```这种构造是立即的并且以线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n·n!) | O(n·n!) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) 不包括输出 | 已接受 |

 ## 算法演练

 1.读取整数`n`。 
2. 构建以以下开头的排列`n`。 

在所有交换之后，该元素必须移动到最后一个位置，因为递归过程会将数组向左旋转一步。 
3. 附加所有整数`1`到`n - 1`按递增顺序。 

在交换引起的左旋转之后，这些元素移动到正确的排序位置。 
4. 打印结果排列。 

### 为什么它有效

 递归函数从左到右执行相邻交换恰好一次。 该序列变换为：```
[a1, a2, a3, ..., an]
```进入：```
[a2, a3, ..., an, a1]
```这是向左旋转一个位置。 

如果我们希望最终的数组变成：```
[1, 2, 3, ..., n]
```那么初始数组必须是逆变换，即已排序数组的右旋转：```
[n, 1, 2, ..., n-1]
```将递归交换应用于此排列会产生排序顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

ans = [n] + list(range(1, n))

print(*ans)
```实现直接遵循数学观察。 

数组开头为`n`因为递归过程将第一个元素移动到末尾。 所有剩余的数字已经按顺序排列，因此在左旋转之后它们变成：```
1 2 3 ... n
```表达式：```
list(range(1, n))
```正确生成数字`1`通过`n - 1`。 

当以下情况出现时，会出现一种微妙的边界条件：`n = 1`。 

在这种情况下：```
list(range(1, 1))
```产生一个空列表，因此最终结果变为：```
[1]
```这是完全正确的。 

不需要模拟交换。 递归行为完全由旋转观察捕获。

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())

    ans = [n] + list(range(1, n))

    print(*ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("1\n") == "1\n", "sample 1"

# custom cases
assert run("2\n") == "2 1\n", "smallest non-trivial case"

assert run("3\n") == "3 1 2\n", "checks left-rotation logic"

assert run("5\n") == "5 1 2 3 4\n", "general case"

expected = "1000 " + " ".join(str(i) for i in range(1, 1000)) + "\n"
assert run("1000\n") == expected, "maximum size input"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 |`1`|`1`| 最小尺寸边界|
 |`2`|`2 1`| 单次交换行为 |
 |`3`|`3 1 2`| 正确的旋转结构 |
