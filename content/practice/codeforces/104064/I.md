 ## 解决方案
 ## 问题理解

 我们得到了多组罗马数字图块。 每个图块都是罗马数字中使用的七个符号之一：M、D、C、L、X、V 和 I。输入告诉我们每个符号有多少个副本。 

我们的任务是将所有这些图块划分为有效罗马数字的集合，其中每个数字都是使用标准罗马规则（包括 IV、IX、XL 等减法形式）从 1 到 3999 的数字的正确表示，但没有超出标准允许的模式。 

我们形成的每个数字都会根据其拼写消耗字母，并且每个图块必须恰好使用一次。 目标是尽量减少我们最终写入的数字数量，同时仍然使用所有图块。 

输出必须首先给出最小数量的数字，然后提供对具有多重性的不同罗马数字字符串的任何有效分解。 

关键限制是图块数量可能非常大，每个字母类型最多 10^18 个。 这立即排除了任何在简单模拟中迭代各个图块或一一构建数字的方法。 任何有效的解决方案都必须根据聚合计数进行操作，并在相对于输入大小的恒定或对数时间内做出每个决定。 

如果有人试图首先贪婪地打包小数字，就会出现一种微妙的失败模式。 例如，优先考虑 I、II、III 等 I 重数字可能会使您陷入低效的分解，其中 M 等高值符号仍然滞留并强制使用额外的数字。 另一个错误是独立对待每个数字位置并贪婪地优化每个位置的值； 罗马数字通过 C 和 M 等共享字母将数字选择结合在一起，因此本地决策可以跨位置交互。 

核心难点在于，每个罗马数字不是一个简单的标量对象，而是一个字母要求的结构化向量，我们必须将一个巨大的向量划分为最少数量的允许向量。 

## 方法

 蛮力视角会将 1 到 3999 之间的每个有效罗马数字视为可能的“物品”，成本为 1，消耗向量为 7 维。 任务变成选择这些项目的多重集，其总和与输入向量匹配，同时最小化项目数量。 

这就像一个多维无界背包，除了目标总和是精确的并且状态空间是巨大的。 即使忽略计数上的巨大界限，表示大总数所需的数字组合数量也使得任何 DP 超过计数都是不可行的。 分支因子本质上是每步有 3999 个选择，即使是长度达到 10^18 的单个贪婪路径也无法逐步模拟。 

结构性突破是停止思考单个数字，而是关注数字对可用字母的“作用”。 每个罗马数字的每个数字位置都是独立构建的：千位、百位、十位和个位。 这意味着每个数字都可以看作四个独立数字模式向量的总和。 

这种独立性表明对完整数字而不是数字的贪婪策略。 如果我们总是选择仍然可以从剩余瓷砖中形成的“尽可能大”的罗马数字，我们就会最大限度地立即消耗稀有的高价值字母，如 M 和 C。关键的观察结果是，一旦选择了特定的数字，在限制字母类型改变最佳可用数字之前，通常最佳的做法是尽可能多地采用它。 这使得该过程从可能数十亿的步骤变成最多几个阶段。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 枚举所有数字 + DP 计数 | 不可能| 不可能| 太慢了 |
 | 贪心一对一构造| O(n·4000) | O(1) | O(1) | 太慢了 |
 | 按最大数字批量贪婪 | O(k·4000) 其中 k ≤ 7-20 | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们预先计算从 1 到 3999 的每个罗马数字，每个字母需要多少个瓷砖。 这给了我们 3999 个固定的 7 维向量。 

然后，我们将剩余的可用图块维护为 7 维向量。 

1. 在每个阶段，我们构建可以由当前剩余瓷砖组成的字典顺序最大的罗马数字。 这是通过逐位尝试来完成的，从千位开始到个位，并在每个位置选择最大的有效数字，其所需的字母不超过剩余的字母。 

选择字典序最大的原因是较高的数字迫使尽早使用 M、C 和其他高价值符号，这些符号是最受限制的资源。 较小的数字往往会留下尴尬的剩余组合，从而增加最终字符串的数量。 

1. 一旦确定了最佳数字模式，我们就计算一次可以复制多少份。 这是最大整数 t，使得 t 乘以其字母向量仍然适合剩余的图块。 具体来说，t是remaining_count[letter]的所有字母除以required_count[letter]的最小值，忽略未使用的字母。 

这个批处理步骤至关重要，因为重复相同的最佳数字不会改变贪婪的选择，直到某些字母类型变得紧张。 

1. 我们输出重数为 t 的数字，从剩余的池中减去 t 乘以其字母向量，然后重复直到消耗完所有图块。 

迭代次数很少，因为每次迭代都会饱和至少一种成为当前最佳数字瓶颈的字母类型，而且只有七种字母类型。 

### 为什么它有效

 在每一步中，我们都会选择当前约束下最大的数字。 任何替代选择要么使用字典顺序较小的数字，要么每个字符串消耗更少的高值符号，这两者都只会增加以后所需的字符串总数。 批处理步骤保留了最优性，因为如果一个数字对于给定状态是最优的，则重复它仍然是最优的，直到限制约束发生变化，而该变化正是在某个字母达到零时，强制使用不同的可行最大数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

letters = ['M', 'D', 'C', 'L', 'X', 'V', 'I']
idx = {c: i for i, c in enumerate(letters)}

# digit expansions per place
ones = ["", "I", "II", "III", "IV", "V", "VI", "VII", "VIII", "IX"]
tens = ["", "X", "XX", "XXX", "XL", "L", "LX", "LXX", "LXXX", "XC"]
hundreds = ["", "C", "CC", "CCC", "CD", "D", "DC", "DCC", "DCCC", "CM"]
thousands = ["", "M", "MM", "MMM"]

def count_roman(s):
    v = [0] * 7
    for ch in s:
        v[idx[ch]] += 1
    return v

# precompute all numerals
numerals = []
for i in range(1, 4000):
    s = thousands[i // 1000] + hundreds[(i // 100) % 10] + tens[(i // 10) % 10] + ones[i % 10]
    numerals.append((s, count_roman(s)))

def build_best(rem):
    best = None
    best_vec = None

    for s, vec in numerals:
        ok = True
        for i in range(7):
            if vec[i] > rem[i]:
                ok = False
                break
        if not ok:
            continue

        if best is None or len(s) > len(best) or (len(s) == len(best) and s > best):
            best = s
            best_vec = vec

    return best, best_vec

def solve():
    rem = list(map(int, input().split()))
    res = []

    while sum(rem) > 0:
        s, vec = build_best(rem)

        t = float('inf')
        for i in range(7):
            if vec[i]:
                t = min(t, rem[i] // vec[i])

        res.append((s, t))

        for i in range(7):
            rem[i] -= vec[i] * t

    print(len(res))
    for s, t in res:
        print(s, t)

if __name__ == "__main__":
    solve()
```该实现首先构建所有有效的罗马数字，并将每个数字转换为字母要求的固定向量。 这`build_best`函数搜索当前可以形成的最佳数字，通过长度和字典顺序进行比较作为“最大”的代理。 

一旦选择了最佳数字，代码就会使用简单的字母计数最小比率来计算适合的副本数量。 尽管存在很大的限制，但这种批处理可以使解决方案保持足够快的速度。 

一个常见的陷阱是忘记在每批之后重新计算最佳数字。 在耗尽单个字母类型后，剩余资源的结构可能会发生巨大变化，尤其是在高数值数字中大量使用的 M 或 C。 

## 工作示例

 ### 示例 1

 输入：```
m d c l x v i = 4 1 7 1 3 1 3
```我们从全部资源开始并计算最大的数字。 假设最好的是`MMCCCXCVIII`。 其消耗向量是固定的。 

| 步骤| 所选数字 | 计数 t | 剩余零钱 |
 | --- | --- | --- | --- |
 | 1 | MMCCCXCVIII | 1 | 减去全向量|
 | 2 | MMDCCCLXX | 1 | 减去全向量|

 此时，剩余的图块已用完，因此我们使用了 2 个不同的数字，每个数字的重数为 1。 

这显示了不同的高值数字如何根据资源的消耗方式出现，以及为什么需要重新计算。 

### 示例 2

 输入：```
0 0 0 300 2000 1000 2100
```这里我们只有较低的符号，因此数字将尽可能避免使用 M、D、C。 

| 步骤| 所选数字 | 计数 t | 剩余零钱 |
 | --- | --- | --- | --- |
 | 1 | 二十五 | 300 | 300 大量消耗L、X、V |
 | 2 | 二十八 | 700 | 完成剩余的 I 和 X |

 这演示了批处理：一次`LXXV`选择后，最好重复它，直到 L 变紧，之后最佳数字的结构发生变化。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(k·3999·7) | 每次迭代都会扫描所有数字并检查 7 个字母 |
 | 空间| 欧(3999) | 数字向量的存储 |

 实际上，迭代次数 k 很小，因为每个批次都会消除当前最佳数字的至少一种限制字母类型。 即使输入幅度高达 10^18，该解决方案也可以在限制内轻松运行，因为昂贵的循环超过固定常数 3999 个数字。

 ## 边缘情况

 当最好的数字使用罕见的字母时，就会出现极端情况，这会立即成为瓶颈。 例如，如果 L 稀缺，而 X 和 I 丰富，则在算法切换到完全不同的结构之前，包含 L 的数字可能仅被选择一次。 批处理机制可以清楚地处理这个问题，因为最小比率立即强制 t = 1。 

另一种情况是当所有剩余的图块仅对应于一种字母类型时，例如仅I图块。 最好的数字退化为重复的“I”，并且批处理正确地生成在一个步骤中重复多次的单个数字，而不是逐一迭代。 

最后，当多个数字的长度相等时，字典顺序的平局打破可确保确定性选择。 即使使用不同的平局打破规则，正确性也得以保留，但输出的一致性取决于稳定的排序。
