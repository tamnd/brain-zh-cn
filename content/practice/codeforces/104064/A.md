 ## 解决方案
 ## 问题理解

 系统隐藏一个长度在1到20之间、由数字和英文字母组成的秘密密码。 我们可以重复提交候选字符串。 每次提交后，交互者都会告诉我们猜测是否正确。 如果不正确，它还会根据从简单的逐字符字符串相等性检查得出的固定计时模型，显示评估比较过程所花费的确切时间。 

关键在于密码检查不是即时的，并且会通过计时泄露结构信息。 当检测到不匹配时，比较会立即停止，并且检查内的每个操作都会贡献已知的毫秒数。 这意味着不同的猜测会产生不同的执行时间，具体取决于在第一次不匹配发生之前有多少个前导字符与隐藏密码匹配。 

目标是使用最多 2500 次猜测来重建密码。 

长度和字母表的限制意味着对所有字符串进行完全穷举搜索是不可能的，因为即使 62^20 也是天文数字。 唯一可用的信号是计时，因此解决方案必须逐字符提取有关密码的信息。 

一种简单的方法是尝试随机猜测或系统枚举所有字符串。 两者都失败了，因为即使将每个位置的长度限制为 20 和 62 个字符，搜索空间也会远远超出允许的查询数量。 

一个微妙的边缘情况是由于等长和不匹配长度比较在时间上表现不同这一事实而产生的。 如果我们忽略长度确定，我们可能会错误地假设固定长度前缀重建策略，并在密码比预期短或长时失败。 另一个问题是，提前终止会使计时变得非线性，因此，除非仔细构建，否则对猜测的时间进行简单平均并不能直接恢复位置。 

## 方法

 暴力破解的观点是将其视为黑盒密码猜测问题。 人们可以按字典顺序枚举所有字符串并查询每个字符串。 这是正确的，但没有希望：即使我们将每个位置的长度限制为最多 20 和 62 个交易品种，最坏情况下的尝试次数也会以 20 为指数，远远超过 2500。 

关键的观察结果是交互器通过计时泄漏了前缀匹配长度。 提供的密码比较的行为就像一个循环，在第一次不匹配时停止。 每个匹配字符都会将运行时间延长可预测的量。 因此，如果我们控制猜测的前缀，我们可以通过观察检查运行的时间来衡量有多少前导字符是正确的。 

这将问题转化为一次重构一个位置的密码。 在每个位置，我们修复已经发现的前缀并尝试所有可能的下一个字符。 正确的字符会产生最长的连续匹配比较，因此在该位置的所有候选字符中观察到的时间最长。 

减少是从对整个字符串的指数搜索到对位置的线性搜索，每个搜索最多需要 62 次试验。 由于密码长度最多为 20，因此查询总数最多为 20 × 62 = 1240，安全在限制范围内。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举| O(62^L) | O(L) | 太慢了 |
 | 前缀时序重建| O(62·L) | O(L) | 已接受 |

 ## 算法演练

 我们假设访问一个函数，该函数返回给定猜测字符串的测量时间。

1. 以空前缀字符串开头。 这代表我们已经重建的密码部分。 在此阶段，我们对密码不做任何假设。 
2. 对于从 1 到 20 的每个位置，尝试将当前前缀扩展一个字符。 我们迭代允许的字母表中所有可能的字符。 每个候选者都会形成一个完整的猜测，我们在哪里附加字符并可选地填充或简单地依赖交互器的长度比较行为。 
3. 对于每个候选字符，提交由当前已知前缀加上该字符组成的字符串。 记录返回时间。 正确性见解是，与真实密码匹配的初始字符越多，比较在失败或完成之前运行的时间就越长。 
4. 选择产生最长观察时间的字符。 该字符必须是密码的正确下一个字符，因为只有正确的扩展名才能在比较过程中保留最长的匹配前缀。 
5. 将选定的字符附加到前缀。 
6. 如果交互者在任何时候响应“已授予访问权限”，则应立即终止，因为密码已完全匹配。 
7. 如果添加更多字符并不能以有意义的方式增加时间，或者重复试验表明已完成，请尽早停止。 实际上，当密码完全匹配时，循环自然结束。 

### 为什么它有效

 密码检查执行顺序比较并在第一次不匹配时停止。 对于任何固定前缀猜测，运行时间随着与隐藏密码共享的正确前缀的长度而严格增加。 在已知正确前缀的所有单字符扩展中，只有正确的下一个字符保留该前缀，因此最大化终止前执行的成功比较的数量。 这会创建一个单调信号：正确的选择对应于比错误的选择严格更高的观察到的运行时间，使得每个位置的贪婪选择都有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import string

alphabet = string.ascii_letters + string.digits

def query(s):
    print(s, flush=True)
    resp = input().strip()
    if resp.startswith("ACCESS GRANTED"):
        sys.exit(0)
    # format: ACCESS DENIED (t ms)
    # time is embedded but not strictly needed
    return resp

def main():
    prefix = ""

    for _ in range(20):
        best_char = None
        best_time = -1

        for c in alphabet:
            guess = prefix + c
            resp = query(guess)

            # extract time
            # format: ACCESS DENIED (t ms)
            try:
                t = int(resp.split("(")[1].split()[0])
            except:
                t = 0

            if t > best_time:
                best_time = t
                best_char = c

        prefix += best_char

        # optional early stop: if last query was already full match,
        # interactor would have exited

    print(prefix, flush=True)

if __name__ == "__main__":
    main()
```该解决方案维护不断增长的前缀，并在每一步尝试所有可能的下一个字符。 交互循环是严格的：每个打印的猜测都必须立即刷新，否则交互器将不会响应，程序将死锁。 

时间提取仅用于比较候选者。 除了排序之外不需要实际的数值，因此即使解析稍微有噪音，相对最大值也保持一致。 

该循环限制为 20 次迭代，因为密码长度最多为 20。在最坏的情况下，每次迭代执行 62 次查询。 

## 工作示例

 考虑隐藏密码`"A7b"`。 

开始时，前缀为空。 我们尝试所有角色。 仅有的`"A"`产生持续较高时间的响应，因为它与密码的第一个字符匹配。 所以`"A"`被选中。 

在第二次迭代中，前缀是`"A"`。 我们尝试`"Aa"`,`"Ab"`,`"A7"`等仅`"A7"`匹配第二个字符，因此它产生最大的时间。 

在第三次迭代中，前缀是`"A7"`。 尝试所有扩展显示`"A7b"`产生最大时间并被接受。 

| 步骤| 前缀| 尝试过 char | 最佳人物 | 观察到的效果 |
 | --- | --- | --- | --- | --- |
 | 1 | “” | 全部 | 一个 | A 产生最长的前缀匹配 |
 | 2 | “A”| 全部 | 7 | A7延长比赛|
 | 3 | “A7”| 全部 | 乙| 已达到完整匹配|

 这演示了时序如何通过将前缀正确性放大为可测量的运行时差异来隔离每个位置的正确字符。 

现在考虑密码`"0Z"`。 

在前缀处`""`，所有第一个字符的猜测都与`"0"`。 仅有的`"0"`产生最长的比较链。 在前缀处`"0"`， 仅有的`"0Z"`产生完整的匹配。 

这表明该方法不依赖于字符类型分布或字母顺序，仅依赖于前缀匹配长度。

 ## 边缘情况

 对于长度为 1 的密码，例如`"G"`，该算法以空前缀开始并尝试所有字符。 仅有的`"G"`产生最大时间，因为它立即匹配不匹配之前的第一个字符。 所选字符成为完整密码，并且该过程在一次迭代中完成。 

对于许多字符与其他候选字符共享长前缀的密码，例如`"abcXYZ"`，所有猜测共享`"abc"`直到位置 4 为止都会表现类似。此时，只有正确的`"X"`扩展产生额外的匹配比较，因此它干净地分离了正确的分支，尽管之前存在歧义。
