 ## 解决方案
 ## 问题理解

 我们被要求改造一系列魔法令牌，使每个令牌都具有奇怪的魔法力量。 每个令牌都以某个正整数幂开始。 我们可以通过融合运算将两个令牌合并为一个，将它们的幂相加，或者我们可以通过将其除以二来减少具有偶数幂的令牌。 目标是确定使所有标记为奇数所需的这些操作的最小数量。 

输入由多个测试用例组成，每个测试用例给出代币的数量及其初始功率。 每个测试用例的输出是一个表示最小操作数的整数。 

约束告诉我们，所有测试用例中的代币总数最多为 200,000 个，并且单个幂可以达到 1e9。 这表明我们需要一种相对于令牌数量以大致线性或线性时间运行的算法。 考虑所有令牌配对的二次解决方案会太慢。 

当所有令牌都是偶数但幂是 2 的不同幂时，就会出现不明显的边缘情况。 例如，`[2, 4, 8]`需要仔细规划：首先盲目地减少少量数量可能比战略性组合代币需要更多的操作。 另一种边缘情况是当所有标记都是奇数时，这需要零运算； 简单的算法可能仍然会尝试不必要的操作。 

## 方法

 暴力方法将模拟所有可能的融合和归约序列，以检查哪个产生最少的操作。 对于每个 Fusion，我们都会尝试每一对令牌； 对于每个归约，我们都会检查每个偶数标记。 虽然这在原则上是可行的，但序列的数量随着标记的数量呈指数增长，使得这种方法不可行。 

最佳方法的关键观察是我们不需要模拟每个序列。 融合仅在组合偶数标记时才有帮助，并且每次归约都会将偶数减半，直到其变为奇数。 每个偶数都可以独立减少，但是如果我们有多个偶数，我们可以通过先融合其中一些来节省操作。 具体来说，最小运算次数取决于偶数令牌被除以二成为奇数所需的最少次数，因为我们总是可以策略性地组合令牌以专注于成本最低的令牌。 

这导致了一种建设性的贪婪策略：对于每个偶数标记，计算我们必须除以二才能达到奇数的次数。 如果多个token需要相同的除法次数，则只需要分别执行除法次数最小的一个； 其他可以与它合并，从而节省操作。 奇数需要进行零运算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 最佳 | O(n log A) | O(n log A) | O(n) | 已接受 |

 这里，`A`是最大代币价值。 每个令牌最多可以除以二`log2(A)`次。 

## 算法演练

 1.读取测试用例的数量。 
2. 对于每个测试用例，请阅读`n`以及象征性权力列表。 
3. 初始化一个空列表来存储每个偶数标记所需的归约操作次数。 
4. 对于每个标记，如果是奇数，则继续下一个。 如果是偶数，则计算必须除以多少次才能成为奇数，并存储该计数。 
5. 如果没有偶数标记，则答案为零。 
6. 否则，按升序对计数进行排序。 第一个计数代表一个令牌所需的最小减少量。 每个后续计数对应于可以合并到流程中的附加令牌，如有必要，可为每个附加令牌添加一个操作。 
7. 对获得使所有令牌成为奇数所需的最小步骤数所需的操作求和。 
8. 打印每个测试用例的答案。 

为什么有效：该算法利用了将最小偶数标记除以最少次数即可实现最少运算的不变量。 将较大的令牌融合到其中不会增加最小减少步骤，因为偶数的融合不会减少达到奇数所需的除法数量。 这种贪心策略保证了总操作数最少。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def min_operations(tokens):
    even_counts = []
    for x in tokens:
        if x % 2 == 0:
            count = 0
            while x % 2 == 0:
                x //= 2
                count += 1
            even_counts.append(count)
    if not even_counts:
        return 0
    even_counts.sort()
    # minimum reductions for the first token + 1 for each remaining even token
    return even_counts[0] + len(even_counts) - 1

t = int(input())
for _ in range(t):
    n = int(input())
    tokens = list(map(int, input().split()))
    print(min_operations(tokens))
```第一个循环收集每个偶数标记除以二的计数。 排序确保我们首先关注需要最少操作的令牌。 添加`len(even_counts) - 1`考虑使用 Fusion 有效地组合剩余的偶数令牌。

 ## 边缘情况

 对于输入`[16, 8, 4]`，该算法计算除法：`16→4`,`8→2`,`4→1`。 排序给出`[1, 2, 3]`。 最少的操作：`1 + 2 = 3`。 这与预期的最小序列匹配：fuse`4`和`8`然后减少，融合`16`并减少，有效地产生所有奇数。 

对于输入`[1, 3, 5, 7]`，所有标记都是奇数。 该算法找不到偶数并返回`0`立即，避免不必要的操作。 这演示了零操作边缘情况的正确处理。
