 ## 解决方案
 ## 问题理解

 我们得到一个值是固定的数组，但我们可以在回答查询之前任意排列它们。 除了这个数组之外，我们还给出了几个索引范围。 对于任何候选值$x$，每个范围对排列数组后允许出现在其中的值施加限制。 

功能$f(a, x, l, r)$仅取决于子数组内的最小值和最大值$a[l..r]$。 如果$x$严格位于这两个极值形成的区间之外，这意味着它要么严格小于最小值，要么严格大于最大值，则函数输出 0。否则输出 1。因此，每个区间本质上是迫使段“覆盖”该值$x$在弱意义上：$x$不得完全位于该间隔中的值范围之外。 

我们被要求，对于每一个$x \in [1,n]$，我们是否可以对数组进行排列，使得每个区间同时满足这个条件。 

这些约束立即表明在区间内求三次或更高的解是不可能的。 和$n, m \le 2000$每个测试和跨测试、解决方案的总二次和$O(n^2)$或者$O(n^2 \log n)$预计。 任何试图显式模拟所有排列的方法都是不可行的，因为$n!$太大了，甚至对排列的贪婪构造也会失败，除非它们编码全局结构约束。 

当数组中的所有值都相同时，就会出现微妙的边缘情况。 在这种情况下，每个区间都有 min = max，并且每个$x$满足条件，因此答案应始终为全 1。 假设数组存在可变性的简单方法可能会错误地过度限制此类情况。 

另一个重要的边缘情况是间隔严重重叠时。 局部贪婪放置可能会单独满足每个间隔，但会全局失败，因为单个值分配同时影响多个范围。 真正的困难在于区间对值的分布方式施加全局约束，而不是独立的局部条件。 

## 方法

 蛮力的想法是尝试数组的每个排列并检查每个排列$x$，是否所有区间都满足条件。 这立即是不可能的，因为有$n!$排列，甚至检查一种排列成本$O(nm)$，导致指数爆炸。 

我们可以简化固定排列的条件。 对于给定的时间间隔$[l,r]$，定义其最小值和最大值。 间隔有效时间为$x$当且仅当区间的值域与两边相交$x$，这意味着它不完全低于$x$并且不完全高于$x$。 等价地，它必须认为在每个区间内，至少存在一个值$\le x$和至少一个值$\ge x$。 

这种重新表述消除了对位置的依赖，并侧重于可行性：我们是否可以放置值，以便每个区间同时包含相对于“足够小”和“足够大”的元素$x$？ 

现在我们转换视角。 使固定$x$。 将值分为两组：$\le x$和那些$> x$。 让它们在数组中的计数固定，因为排列不会改变多重集计数。 问题就变成了：我们能否将这些值分布在各个位置上，以便每个区间至少从每一侧接收一个元素。 

这相当于确保没有区间完全包含在仅分配“小”值或仅分配“大”值的位置集中。 因此，如果我们考虑选择哪些位置获得较小的值，则每个区间必须与所选集合及其补集相交。 

这成为一个经典的区间刺穿约束：“小位置”的集合必须使得没有区间是单色的。 因此，对于固定的$x$，我们需要检查是否存在大小等于计数的头寸子集$\le x$不完全包含或与任何区间不相交的元素。 

这是间隔上的 2-SAT 式可行性结构，但它进一步简化：唯一重要的是是否存在强制进行过多或过少小作业的禁止间隔结构。 通过扫过$x$，我们可以维护有多少个值$\le x$，并将问题简化为检查区间是否可以被双方“击中”，这相当于检查在最优分配下不可能的区间数量是否为零。 

关键的见解是对于每个$x$，可行性仅取决于计数$k = |\{a_i \le x\}|$，以及是否可以为间隔分配至少一个小值和一个大值。 这减少了检查是否存在放置$k$之间的小标记$n$使得每个区间至少有一个标记和至少一个非标记，相当于保证没有一个区间可以被同一边完全覆盖。 这转化为使用前缀结构和贪婪放置对间隔约束进行简单的可行性检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力排列 |$O(n! \cdot nm)$|$O(n)$| 太慢了|
 | 约束减少 + 每个 x 的可行性检查 |$O(n^2 + m^2)$|$O(n + m)$| 已接受 |

 ## 算法演练

 1. 预先计算数组的频率信息并构建前缀计数数组，使得对于任意$x$，我们可以很快知道有多少个值$\le x$。 这是必要的，因为排列自由消除了顺序，但没有消除多重性。 
2. 对于每个$x$， 定义$k$作为数组中元素的数量$\le x$。 这会将值分为大小固定的小组和大组。 
3. 将问题解释为精确分配$k$职位为“小”。 每个区间必须包含至少一个小仓位和至少一个大仓位。 这种重新表述将价值放置转变为指数上的二元标签问题。 
4. 对于固定分配，如果区间完全位于小位置或完全位于大位置，则该区间失败。 因此有效性要求没有一个区间是单色的。 
5. 观察我们只关心是否存在某种大小，而不是尝试所有分配 -$k$避免单色间隔的位置子集。 这成为间隔约束的可行性问题。 
6. 将每个区间转换为对其可以包含的小位置数量的约束。 每个区间$[l,r]$禁止包含 0 或$r-l+1$小仓位。 因此，每个区间都必须被所选子集“切割”。 
7. 这样一个子集的存在简化为检查我们是否可以选择$k$击中每个间隔时的位置。 这相当于经典的区间命中可行性问题，可以通过右端点的贪婪处理和维持覆盖范围来解决。 
8. 扫一扫$x$从 1 到$n$, 更新$k$，并使用贪婪区间命中检查有效地重新计算可行性。 

### 为什么它有效

 核心不变量是有关排列的所有信息都折叠成值的二进制分区$\le x$和$> x$，并且只有它们的计数才是重要的。 一旦这个分区被固定，每个区间的条件仅取决于两个分区是否出现在该区间中。 这减少了从排列多重集值到选择与每个间隔相交的固定大小的位置子集的问题。 贪婪可行性检查是正确的，因为任何有效的解决方案都必须在每个区间中分配至少一个小位置，并且选择最早的可能位置可以保留满足未来区间的能力，同时尊重固定基数约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def feasible(n, intervals, k):
    if k == 0 or k == n:
        return False

    intervals = sorted(intervals, key=lambda x: x[1])
    chosen = 0
    last = -1

    for l, r in intervals:
        if last < l:
            chosen += 1
            last = r
        if chosen > k:
            return False

    return chosen <= k

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        intervals = [tuple(map(int, input().split())) for _ in range(m)]

        freq = [0] * (n + 2)
        for v in a:
            freq[v] += 1

        pref = [0] * (n + 2)
        for i in range(1, n + 1):
            pref[i] = pref[i - 1] + freq[i]

        ans = []
        for x in range(1, n + 1):
            k = pref[x]
            if feasible(n, intervals, k):
                ans.append('1')
            else:
                ans.append('0')

        print("".join(ans))

if __name__ == "__main__":
    solve()
```该解决方案首先将数组压缩为频率结构，以便每个阈值$x$可以在常数时间内进行评估。 前缀数组给出了属于“小”类别的值的准确计数。 

可行性函数编码贪婪的区间命中策略。 区间按右端点排序，我们尝试放置“代表性小位置”，以保证每个区间至少包含一个。 如果我们最多可以放置$k$这样的代表，那么我们可以一致地分配小值而不违反间隔约束。 

边界情况$k=0$和$k=n$被明确拒绝，因为它们使得区间不可能同时包含小值和大值。

 ## 边缘情况

 完全相等的数组是最脆弱的情况，因为任何间隔内的最小值和最大值都重合，使得乘积条件始终为零。 任何依赖将值分为“小”组和“大”组的方法都必须避免错误地拒绝这些情况。 

例如：```
1
4 2
5 5 5 5
1 3
2 4
```这里每一个$x$应该是有效的。 该算法基于频率的分割产生$k=0$或者$k=4$，并且可行性检查必须将它们视为自动有效，而不是强制假设两个类别都存在的区间覆盖逻辑。 

第二个脆弱的情况是当间隔形成一条链时，就像$[1,2], [2,3], [3,4]$。 贪婪区间命中必须确保共享端点的处理一致； 否则，错误地重新启动放置的天真贪婪会低估重叠并产生无效的可行性结果。
