[CF 432A - 选择团队](https://codeforces.com/problemset/problem/432/A)

 **评分：** 800
 **标签：** 贪婪、实现、排序
 **求解时间：** 1m 21s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们有一所大学的一组学生，每个学生都有参加 ACM ICPC 世界锦标赛多少次的记录。 培训中心的负责人希望组建正好三名学生的队伍，并且要求每个队伍至少参加_k_次世界锦标赛。 一名学生不能加入多个团队。 

输入由两个整数组成，_n_（学生人数）和 _k_（团队未来所需参与的最少人数）。 第二行给出 _n_ 个整数，其中每个整数代表学生已经参与的次数。 由于任何学生最多可以参加五次，因此只有当学生过去的参加次数与 _k_ 之和不超过 5 时，才可以为团队做出贡献。 

输出是一个数字：在这些限制下可以组建的三人团队的最大数量。 

约束告诉我们 _n_ 可以达到 2000，这对于简单的 O(n log n) 或 O(n) 算法来说足够小。 然而，尝试考虑三个学生的所有子集的简单方法将需要 O(n³) 运算，这显然太慢了。 

不明显的边缘情况包括一些学生已经达到参与限制并且无法加入任何新团队的情况。 例如，如果输入是`3 1`有参与`5 5 5`，无法组队，所以正确的输出是`0`。 忽视参与上限的粗心方法可能会错误地将团队视为有效团队。 

## 方法

 暴力方法将迭代三个学生的所有可能组合，并检查每个组合是否满足参与约束。 这种方法原则上是正确的，因为它详尽地检查了所有选项，但最坏情况的组合数是`C(n,3)`，大约为n3/6。 对于 _n_ = 2000，这超过了十亿次检查，这对于 1 秒的时间限制来说太慢了。 

最佳解决方案来自于我们不需要明确检查每个组合的观察。 重要的是学生是否有资格加入团队。 如果我们算一下最多参加的学生人数`5 - k`有时，这些学生中的任何三个都可以组成一个团队。 这将问题简化为计算符合条件的学生，然后除以三，丢弃余数，因为少于三人的团队无法组成。 

这种见解将组合问题转化为简单的计数问题。 我们只迭代学生列表一次，使其在时间上呈线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(n) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从输入中读取 _n_ 和 _k_。 这些定义了团队所需的学生人数和未来参与的最低人数。 
2. 阅读学生参与计数列表。 每次计数都会告诉我们学生已经参加了多少次。 
3. 将符合条件的学生的计数器初始化为零。 符合资格的学生是指能够参加至少 _k_ 次但不超过最多 5 次的学生。 
4. 迭代每个学生的参与计数。 对于每个学生来说，如果`count + k ≤ 5`，增加符合条件的计数器。 此步骤过滤掉超出参与限制的学生。 
5. 参赛队伍的最大数量为符合资格的学生人数除以三的整数。 我们丢弃其余的，因为少于三名学生无法组成团队。 
6. 打印最终的队伍数量。 

为什么有效：在每一步中，我们都保持不变，即只考虑有资格组建团队的学生。 通过将符合资格的学生总数除以三，我们确保组成的每个团队恰好由三名符合资格的成员组成。 符合条件的学生不会被计算两次，满足“多个团队中没有学生”的约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
participations = list(map(int, input().split()))

eligible_count = 0
for p in participations:
    if p + k <= 5:
        eligible_count += 1

max_teams = eligible_count // 3
print(max_teams)
```该解决方案使用有效地读取输入`sys.stdin.readline`处理潜在的大输入。 该循环使用简单的条件过滤符合条件的学生，通过使用避免差一错误`<= 5`。 整数除法确保不会计算不完整的团队。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    participations = list(map(int, input().split()))
    eligible_count = sum(1 for p in participations if p + k <= 5)
    return str(eligible_count // 3)

 ## 边缘情况

 在输入中`3 1\n5 5 5`，算法迭代参与并发现没有学生符合资格，因为`5 + 1 > 5`。 符合条件的计数器保持为零，整数除以 3 得到 0。这正确处理了所有学生都处于参与限制的边缘情况。 

在输入中`2 1\n0 1`，计数器找到 2 名符合条件的学生，但除以 3 得出 0，正确处理了少于 3 名学生的情况。 

该解决方案一致地处理边界和参与限制，确保不会过度计数团队。
