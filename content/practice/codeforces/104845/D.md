 ## 解决方案
 ## 问题理解

 我们维护一个非常大的数组，索引可达$10^9$，但只有第一个$n$位置最初非零。 所有剩余位置都隐式为零。 每个位置保存一个 30 位整数。 

有两个操作。 首先，我们可以将单个位置更新为新值。 其次，我们被要求统计有多少个非负整数$x$满足全局按位约束：如果我们将每个数组元素与$x$，结果不超出给定范围$z$。 

关键的观察结果是，所有数组元素上的 OR 将整个结构折叠成单个值。 如果我们定义$$S = a_1 \,|\, a_2 \,|\, \cdots \,|\, a_n,$$那么每个额外的零元素都没有贡献，所以全局 OR 恰好是$S$。 添加后$x$，条件变为$$S \,|\, x \le z.$$约束条件很大：最多$10^5$更新和查询，并且值适合 30 位。 如果涉及到所有元素，则任何从头开始重新计算每个查询的 OR 的解决方案都会太慢，因为这会产生成本$O(nq)$，这大约是$10^{10}$最坏情况下的操作。 

一个微妙的点是更新可以发生在任意索引处，最多可达$10^9$，但只有最初提供的指数才重要。 任何其他位置都永久为零，因此在概念上可以忽略初始集之外的更新，除非它们引用初始集$n$或者以更一般的解释扩展活动集。 

当位取消或重新出现时，会出现边缘情况：

 如果所有值都变为零，则条件简化为$x \le z$, 给予$z+1$解决方案。 如果$S$已经超过$z$，没有值$x$可以修复较高位$S$，所以答案为零。 

## 方法

 直接方法维护完整数组并为类型 2 的每个查询重新计算 OR。这是正确的，因为 OR 是结合性和交换性的，因此从头开始重新计算总是会产生正确的结果$S$。 但是，每个查询需要扫描最多$n$元素，导致$O(nq)$工作。 和$n,q \approx 10^5$，这变得太慢了。 

关键的结构见解是“或”每位的表现都是单调的。 每个位在全局状态中要么存在，要么不存在，并且仅更新固定集中的切换位。 我们不需要知道查询类型 2 的各个元素，只需要知道当前的全局 OR$S$。 

所以我们维护一个位掩码$S$。 对于更新，我们必须调整$S$当元素发生变化时。 如果替换某个值，并且该值是这些位的最后贡献者，则某些位可能会从 OR 中消失。 这需要跟踪每个比特当前包含多少个元素。 

我们维护一个大小为 30 的频率数组来表示位数。 更新元素时​​，我们会减少其旧值的计数并增加其新值的计数。 如果计数变为正数，则通过设置一个位来更新全局 OR，如果计数变为零，则将其清除。 

一次$S$已知，每个查询都减少为计数$x$这样$$S \,|\, x \le z.$$这是一个经典的位约束计数问题。 对于任何一点$S$有一个 1，结果已经有一个 1，无论$x$。 如果$z$那个位置有0，那是不可能的。 否则，这些位将被强制。 对于位，其中$S$有 0,$x$必须保持在规定的限制内$z$，并且计数减少为仅在以下位置自由选择：$z$有 1 和$S$有 0 个。有效数量$x$因此是：$$2^{\text{count of bits } i \text{ where } S_i = 0 \text{ and } z_i = 1}$$如果所有位都在$S_i = 1$满足$z_i = 1$，否则为零。 

这将每个查询减少到$O(30)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力重新计算 OR 每个查询 |$O(nq)$|$O(n)$| 太慢了 |
 | 维持位计数+按位计数 |$O((n+q)\cdot 30)$|$O(n)$| 已接受 |

 ## 算法演练

 我们仅将活动数组视为第一个$n$元素，因为其他位置为零并且不相关。 

1.读取初始数组并计算30位频率数组`cnt`在哪里`cnt[b]`是当前有多少个数字$b$放。 这让我们可以在不扫描数组的情况下重建全局 OR。 
2. 构建初始 OR 掩码$S$通过设置位$b$如果`cnt[b] > 0`。 这会将整个数组状态压缩为单个整数。 
3. 对于每个更新查询$1\ i\ v$, 检索位置处的旧值$i$。 对于每一位$b$，如果设置为旧值，则递减`cnt[b]`。 然后对于新值，增加相应的位。 调整计数后，仅重新计算受影响的位$S$： 少量$b$设置于$S$如果`cnt[b] > 0`。 这确保了$S$始终反映所有元素的真实或。 
4. 对于每个查询$2\ z$，首先检查可行性：如果$(S \& \sim z) \ne 0$，那么需要一些位$S$但被禁止$z$，所以答案为零。 
5. 否则，迭代所有位，其中$S$有零。 对于每个这样的位$b$， 如果$z$有位$b$，它是免费的并贡献一个自由度。 答案是$2^{k}$， 在哪里$k$是此类空闲位的数量。 

### 为什么它有效

 该算法保持一个不变量：`cnt[b] > 0`当且仅当位$b$存在于至少一个有源阵列元件中。 因此保养的面膜$S$始终是所有当前元素的按位或。 

一次$S$是固定的，每个位的位置$x$独立贡献。 有点设定$S$强制相同的位$z$为 1； 否则不存在解决方案。 位在哪里$S$为 0 不施加下限，仅受以下约束$z$。 由于每个这样的位都可以自由选择$x$，位的独立性产生纯粹的二次幂计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    MAXB = 30
    cnt = [0] * MAXB
    
    for v in a:
        for b in range(MAXB):
            if v >> b & 1:
                cnt[b] += 1
    
    S = 0
    for b in range(MAXB):
        if cnt[b] > 0:
            S |= (1 << b)
    
    for i in range(n):
        pass  # placeholder; a is used directly
    
    for _ in range(int(input())):
        tmp = input().split()
        t = int(tmp[0])
        
        if t == 1:
            i = int(tmp[1]) - 1
            v = int(tmp[2])
            old = a[i]
            
            for b in range(MAXB):
                if old >> b & 1:
                    cnt[b] -= 1
                if v >> b & 1:
                    cnt[b] += 1
            
            a[i] = v
            
            S = 0
            for b in range(MAXB):
                if cnt[b] > 0:
                    S |= (1 << b)
        
        else:
            z = int(tmp[1])
            
            if S & ~z:
                print(0)
                continue
            
            free_bits = 0
            for b in range(MAXB):
                if not (S >> b & 1) and (z >> b & 1):
                    free_bits += 1
            
            print(1 << free_bits)

if __name__ == "__main__":
    solve()
```核心结构将状态维护与查询评估分开。 数组`cnt`跟踪每比特的存在，同时`S`每次更新后都会根据它重新计算。 这避免了维护复杂段结构的需要，因为该操作纯粹基于“或”。
