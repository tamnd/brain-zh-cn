 ## 解决方案
 ## 问题理解

 我们有一个餐馆网络，其中边代表“邻居”关系。 有些餐厅一开始就与 Timur 合作。 从这些最初的采用者开始，合作可以传播：任何餐厅也会决定合作，如果至少$k$其邻国已经开始合作。 

这不是一次性决定。 随着越来越多的餐厅开始合作，它们可能会导致更多的餐厅跨过门槛，因此这个过程会持续下去，直到没有新的餐厅可以激活为止。 

任务是从初始集合开始，确定传播稳定后哪些餐厅最终会合作。 

该图最多可以包含$2 \cdot 10^5$节点和边，因此任何解决方案在边数上都必须接近线性。 每一步对所有节点进行二次模拟会太慢，因为重复扫描邻居会导致$O(nm)$密集情况下的行为。 

出现微妙的边缘情况时$k = 0$。 在这种情况下，无论邻居如何，每家餐厅都会立即符合资格，因此最终答案通常是所有节点。 任何仍然尝试模拟传播的实现都必须小心处理这个问题，否则可能会过于复杂或错误计数。 

另一个值得注意的情况是初始集合为空时。 那么没有餐厅有任何激活的邻居，所以除非$k = 0$，没有任何东西可以被激活。 

## 方法

 考虑这个过程的天真的方法是重复扫描所有餐厅并检查每家餐厅是否已经满足“至少$k$活跃邻居”。每次我们找到满足它的新餐厅时，我们都会激活它并重新启动扫描。

 这是正确的，因为它直接反映了规则定义。 然而，问题是性能。 每次扫描所有节点的成本$O(n + m)$如果我们计算邻居检查，在最坏的情况下，我们可能会一次激活一家餐厅，从而导致$O(n)$回合。 这给出了$O(n(n + m))$，对于$n, m \le 2 \cdot 10^5$。 

关键的观察是我们永远不需要从头开始重新计算完整的邻居计数。 重要的是每家餐厅目前有多少已经活跃的邻居。 这建议为每个节点维护一个运行计数器，并在邻居变为活动状态时增量更新它。 

一旦我们以这种方式看待它，该过程就成为图上的标准传播。 我们从所有最初活动的节点开始，将它们推入队列，并且对于每次激活，我们更新其邻居。 每当邻居的活跃计数达到$k$，它变得活跃并且也被推入队列。 

这将过程转变为广度优先样式扩展，其中仅当一个端点变为活动状态时才处理每条边。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n(n + m))$|$O(n + m)$| 太慢了 |
 | 最优 BFS 传播 |$O(n + m)$|$O(n + m)$| 已接受 |

 ## 算法演练

 我们将该图解释为邻接表。 每个节点都维护一个计数器，用于跟踪有多少邻居已经处于活动状态。 

1. 从输入边构建图的邻接表。 这是必需的，以便我们可以在节点变为活动状态时有效地遍历邻居。 
2. 创建数组`cnt`所有节点都初始化为零。 这将存储每个节点当前有多少个活动邻居。 
3.初始化布尔数组`active`在哪里`active[i]`如果餐厅为真$i$一开始就已经合作了。 这些节点形成传播的初始边界。 
4. 将所有初始活动节点插入队列。 这些是唯一可以立即影响其他节点的节点。 
5. 当队列不为空时，提取一个活动节点$u$。 为每一位邻居$v$的$u$, 增量`cnt[v]`增加 1 是因为它的另一个邻居变得活跃。 
6. 如果`cnt[v]`准确地达到$k$和$v$尚未激活，标记$v$为活动状态并将其推入队列。 当这一切发生的那一刻，$v$成为邻国影响力的新来源。 
7. 继续，直到队列耗尽。 此时，不再有不活动节点达到阈值，因此该过程是稳定的。 

### 为什么它有效

 该算法保持了每个节点的不变性，`cnt[v]`总是等于邻居的数量$v$已在流程的当前点激活。 每个激活事件只会增加这些计数器，而不会减少它们，这与扩展规则的单调性质相匹配。 

一旦节点的真实活跃邻居数量达到至少，该节点就会变得活跃$k$。 由于计数器在邻居激活时立即更新，因此不会错过任何符合条件的节点，也不会过早激活任何节点。 队列确保激活以正确的因果顺序传播，相当于重复应用原始规则直到达到固定点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, k = map(int, input().split())
    
    adj = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)
    
    initial = list(map(int, input().split()))
    if len(initial) == 1 and initial[0] == 0:
        initial = []
    
    if k == 0:
        print(n)
        print(*range(1, n + 1))
        return
    
    active = [False] * (n + 1)
    cnt = [0] * (n + 1)
    
    q = deque()
    
    for x in initial:
        if not active[x]:
            active[x] = True
            q.append(x)
    
    while q:
        u = q.popleft()
        for v in adj[u]:
            if active[v]:
                continue
            cnt[v] += 1
            if cnt[v] >= k:
                active[v] = True
                q.append(v)
    
    res = [i for i in range(1, n + 1) if active[i]]
    
    print(len(res))
    print(*res)

def main():
    solve()

if __name__ == "__main__":
    main()
```邻接表以标准方式构建，确保每条边存储两次，因为图是无向的。 这`cnt`数组是跟踪阈值条件进展的中心机制。 

该队列恰好包含刚刚变为活动状态的节点。 每个节点都会被处理一次，一旦处理完毕，它就不会重新进入队列，因为激活是永久性的。 这确保了线性复杂度。 

一个小的实现细节是早期处理$k = 0$，这完全避免了不必要的图形处理。 另一个微妙的点是确保我们不会重新添加已经活动的节点，否则会错误地增加计数。

 ## 边缘情况

 一个关键的边缘情况是$k = 0$。 在这种情况下，无论图结构如何，每个餐厅都会立即满足条件。 该算法通过直接打印所有节点而不处理图形来处理此问题。 例如，对于任何输入图和$k = 0$，输出必须始终是全套$1 \ldots n$，并且跳过 BFS 可以防止不必要的工作。 

另一种情况是初始集为空且为正$k$。 在这种情况下，任何节点都无法获得活动邻居，因此队列开始为空，并且该过程立即结束。 该不变量成立是因为所有计数器都保持为零，永远不会达到阈值。 

最后，考虑一个度小于的节点$k$。 此类节点永远无法激活，除非它们最初处于活动状态。 计数器机制自然会强制执行此操作，因为`cnt[v]`永远无法超过它的程度，所以它永远无法达到$k$如果$k$更大。
