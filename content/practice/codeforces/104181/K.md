 ## 解决方案
 ## 问题理解

 我们维护一个动态的整数集合，每个整数代表一种化学物质。 随着时间的推移，我们将新值插入到该集合中。 在任何时候，我们都可以通过采用当前可用化学物质的任何子集并将所有选定元素异或在一起（包括产生 0 的空子集）来形成新值。 

每个类型二的查询都会给我们一个酸值`a`和目标掩模`b`。 我们想知道是否存在某种价值`c`可以由当前集合的子集 XOR 形成，这样的按位 AND`c`和`a`正好等于`b`。 

因此，核心对象是所有插入数字的异或跨度，每个查询询问我们是否可以在这个异或空间中实现一个向量，该向量投影到位掩码上`a`等于`b`。 

这些约束最多可达 100,000 次操作，因此任何针对每个查询重新计算整个 XOR 子集空间的解决方案都是不可行的。 完整的子集空间随着插入元素的数量呈指数增长，甚至显式地表示它也变得不可能。 

一种天真的方法会尝试维护所有可到达的 XOR 值并针对它们测试每个查询，但即使在 30 次插入之后，集合大小也已经变得天文数字般大。 另一个幼稚的错误是将集合视为基础，但忘记查询仅依赖于按位约束，而不是完全相等。 

出现微妙的边缘情况时`a`其位点超出了可用化学品的范围。 例如，如果所有插入的数字仅使用较低位，但是`a`包括一个高位和`b`要求它为 1，无论子集异或如何，答案都立即不可能。 许多不正确的解决方案都忽略了这个投影约束。 

## 方法

 关键的观察结果是，虽然子集 XOR 形成了一个很大的空间，但它们在 GF(2) 上形成了一个线性子空间。 每个插入的数字都构成一个基，任何可实现的异或都是基向量的线性组合。 

这意味着我们不关心所有子集，只关心集合的异或基础。 保持超过 30 位的线性基础使我们能够准确地表示所有可能的 XOR 结果的集合。 

查询条件`c & a = b`限制位`c`在位置上`a`有 1s。 对于每一个位点`a`是 1，我们要么要求`c`匹配`b`或允许自由时`a`是 0。这将问题分解为投影子空间上的约束。 

我们可以考虑构建`c`仅在以下位置逐位`a`很重要。 对于外部位`a`，我们不在乎什么`c`确实如此，因此这些位是自由变量，始终可以使用可用的基向量进行调整。 

关键的减少是我们只需要检查基础是否可以生成与约束一致的值。 这成为具有固定位约束的 30 维 XOR 空间中的可达性问题，可以通过在此基础上使用高斯消除逻辑贪婪地尝试满足所需的位来解决。 

我们从高到低处理位，试图构造一个有效的`c`使用基础，同时尊重强制位`b`。

 | ---| ---| ---| ---|
 | 暴力子集枚举 | 每个查询 O(2^n) | O(2^n) | O(2^n) | 太慢了 |
 | 异或线性基 | O(30q) | O(30) | 已接受 |

 ## 算法演练

 我们维护超过 30 位的二进制线性基础。 

1.初始化一个数组`basis[30]`在哪里`basis[i]`存储一个向量，其最高设置位是`i`。 这确保每个数字都被简化为规范表示。 
2. 对于每次插入`c`，从位 29 向下迭代到 0。如果位`i`设置于`c`， 和`basis[i]`是空的，我们存储`c`在那里停下来。 如果`basis[i]`已经存在，我们进行异或`c`和`basis[i]`消除该位并继续。 此步骤确保所有基向量保持独立。 
3. 回答询问`(a, b)`，我们尝试确定是否存在某种异或组合`c`满足`(c & a) = b`。 
4. 首先，我们验证所需位的一致性`b`。 如果一个位是 1`b`，它也必须是 1`a`，否则这是不可能的，因为`c & a`不能引入不在其中的位`a`。 
5. 我们通过尝试使用基础来匹配位上所需的贡献，从而在受约束的位上构建目标模式，其中`a`是 1。 
6. 我们贪婪地尝试首先使用基向量消除高位，有效地检查我们是否可以构造一个投影匹配的向量`b`。 

### 为什么它有效

 插入数字的所有异或组合的集合形成了 GF(2) 上的向量空间。 维护的基础是该空间的完整等级表示，因此每个可实现的`c`对应于基向量的某个子集。 条件`(c & a) = b`是仅限于选定坐标的线性约束系统。 检查可行性简化为确定系统在基跨越的子空间中是否有解，位高斯消除正确地决定了该解。 由于每次变换都保留了可达空间的等价性，因此不会丢失任何有效的构造。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class XorBasis:
    def __init__(self):
        self.b = [0] * 30

    def insert(self, x):
        for i in range(29, -1, -1):
            if not (x >> i) & 1:
                continue
            if self.b[i] == 0:
                self.b[i] = x
                return
            x ^= self.b[i]

    def can_build_projection(self, a, b):
        # check impossible bits
        if b & ~a:
            return False

        # try to build a value consistent with constraints
        x = 0
        for i in range(29, -1, -1):
            if (a >> i) & 1:
                # we want bit i of (x & a) to match b
                # so we try to control x[i]
                if ((x >> i) & 1) != ((b >> i) & 1):
                    if self.b[i] == 0:
                        return False
                    x ^= self.b[i]
        return True

def main():
    q = int(input())
    xb = XorBasis()
    out = []

    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            xb.insert(tmp[1])
        else:
            _, a, b = tmp
            out.append("YES" if xb.can_build_projection(a, b) else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```插入逻辑是标准XOR基础维护。 每个数字都会被现有的基向量减少，直到它变为零或引入新的主元位。 

查询逻辑首先检查结构不可能性：if`b`有一点外面`a`, 没有构建`c`可以满足 AND 条件。 然后，我们贪婪地从高到低修复位，每当与构建的候选者不一致时，使用基向量翻转构造的候选者中的位`b`。 

贪婪的本质是有效的，因为较高位主导着基础的规范表示，因此较高索引的决策不会在以后撤销。

 ## 边缘情况

 一个关键的边缘情况是当`b`包含不存在于`a`。 例如，`a = 2 (10)`,`b = 3 (11)`立即不可能，因为`(c & 2)`永远不能产生最低位。 支票`b & ~a`直接处理这个问题，并且算法在任何基础推理之前都会拒绝它。 

另一种情况是没有插入化学品时。 唯一可构造的值是 0，因此任何查询都简化为检查是否`(0 & a) == b`，只有当`b = 0`。 基础开始时为空，每当无法生成所需的位时，贪婪构造自然会失败，除了微不足道的情况外，都会正确返回 NO。
