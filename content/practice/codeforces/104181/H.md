 ## 解决方案
 ## 问题理解

 我们有一个非常大的网格，概念上的大小$10^9 \times 10^9$，但我们从不明确地使用它。 相反，我们被告知$N$在此网格上绘制的非重叠轴对齐矩形。 每个矩形都贡献一组最初绘制的单位单元。 

画完之后，$M$选择特定的列索引，并且位于任何这些列中的每个绘制的单元格都会被雨水擦除。 任务是计算删除后剩余多少个绘制的晶胞。 

关键的观察结果是网格太大而无法直接表示，因此所有推理都必须在矩形和删除的列上完成。 

这些约束立即排除了任何单元级模拟。 单个矩形最多可以覆盖$10^{18}$细胞，和$N, M$上升到$2 \cdot 10^5$，因此任何触及每个单元格或将矩形扩展为点的算法都是不可能的。 即使跨所有矩形的每列扫描也会降级为$O(NM)$，这远远超出了限制。 

当矩形很窄或删除的列与许多矩形相交时，会出现微妙的边缘情况。 例如，如果所有矩形都是宽度为 1 的垂直条带，则每个删除查询最多影响每个矩形的一列，并且每次删除后的简单的每个矩形重新计算都会变成二次方。 

另一个陷阱是假设矩形之间的重叠可以独立忽略。 它们是不相交的，但操作是基于列的，因此不同的矩形仅通过共享列索引进行交互，而不是通过区域重叠进行交互。 这意味着正确性取决于矩形之间的每列聚合，而不是每个矩形独立的减法。 

## 方法

 直接的方法是计算所有矩形的总面积，然后对于每个删除的列，减去该列中绘制的单元格的数量。 由于矩形不重叠，计算总面积很简单。 困难在于计算每一列中有多少个绘制的单元格。 

如果我们修复一个列$x$，我们需要检查所有矩形以及跨越这些矩形的总贡献$x$。 每个矩形贡献其高度$r_2 - r_1 + 1$如果它覆盖了列$x$。 对每个移除的色谱柱执行此操作的成本$O(NM)$，可以达到$4 \cdot 10^{10}$运营。 

关键的结构见解是每个矩形在连续的列间隔上贡献一个恒定值。 对于跨越列的矩形$[c_1, c_2]$，该范围内的每一列都获得与其高度完全相同的垂直贡献。 因此，我们不是考虑每列的每个矩形，而是反转视角：我们希望在 x 轴上的间隔内累积贡献。 

这将问题转化为对具有范围添加的列进行一维扫描。 我们将每个矩形转换为 x 轴上的间隔更新和等于其高度的权重。 然后我们只需要评估特定查询列的值，并从总面积中减去这些值。 

因为坐标达到$10^9$，我们压缩所有相关的 x 值：矩形边界和删除的列。 压缩后，我们可以使用差异数组或前缀和来有效计算每个列位置的总绘制高度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个查询的暴力破解 |$O(NM)$|$O(1)$| 太慢了 |
 | 坐标压缩+扫描/差值数组|$O((N+M)\log(N+M))$|$O(N+M)$| 已接受 |

 ## 算法演练

 我们将问题简化为计算被移除的每列中存在多少个绘制单元，并从总绘制区域中减去该值。 

1. 通过对每个矩形的宽度乘以高度求和来计算总绘制面积。 由于矩形不重叠，因此这个总和是精确的。 
2. 从矩形边界和删除的列中提取所有相关的 x 坐标。 这是唯一会发生变化的位置。 
3. 将这些坐标排序并压缩到更小的索引空间中。 每个原始列索引都映射到一个压缩索引。 
4. 在压缩的 x 轴上构建差异数组。 对于每个矩形$[c_1, c_2]$与高度$h = r_2 - r_1 + 1$，我们添加$+h$在开始索引处$c_1$和$-h$就在之后$c_2$。 这编码了间隔中的每一列都会收到额外的垂直贡献$h$。 
5. 将差值数组转换为前缀和数组。 此时，每个压缩坐标都具有覆盖该列的所有矩形贡献的总绘制高度。 
6. 对于每个删除的列，将其映射到其压缩索引并从答案中减去相应的贡献。 
7. 输出最终值。 

我们使用差异更新而不是直接标记范围的原因是，直接标记需要更新每个矩形间隔内的每个压缩位置，这在最坏的情况下仍然太慢。 差异数组将每个矩形减少为两次更新。 

### 为什么它有效

 每个矩形沿 x 轴独立贡献，因为矩形在 2D 空间中不重叠，但允许在 x 轴上的投影重叠。 对于任何固定列，绘制的单元格数量等于覆盖该列的所有矩形的高度之和。 差异数组精确地编码了每列的总和，而前缀总和则为每个位置正确地重建了它。 由于每次删除仅取决于该列的值，因此减去这些值将准确删除已擦除的绘制单元格，而不会重复计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    
    rects = []
    xs = []
    
    total_area = 0
    
    for _ in range(N):
        r1, c1, r2, c2 = map(int, input().split())
        h = r2 - r1 + 1
        w = c2 - c1 + 1
        total_area += h * w
        
        rects.append((c1, c2, h))
        xs.append(c1)
        xs.append(c2)
    
    bad = []
    for _ in range(M):
        x = int(input())
        bad.append(x)
        xs.append(x)
    
    xs = sorted(set(xs))
    idx = {x: i for i, x in enumerate(xs)}
    
    n = len(xs)
    diff = [0] * (n + 1)
    
    for c1, c2, h in rects:
        l = idx[c1]
        r = idx[c2]
        diff[l] += h
        diff[r + 1] -= h
    
    cur = 0
    col_val = [0] * n
    for i in range(n):
        cur += diff[i]
        col_val[i] = cur
    
    removed_sum = 0
    for x in bad:
        removed_sum += col_val[idx[x]]
    
    print(total_area - removed_sum)

if __name__ == "__main__":
    solve()
```该解决方案首先直接根据矩形尺寸计算完整的绘制区域。 这是安全的，因为不存在重叠，因此不需要校正。 

接下来，所有 x 坐标都被压缩。 这是至关重要的，因为坐标达到$10^9$，并且任何基于数组的结构都必须减少到最多$O(N+M)$尺寸。 

差异数组对沿 x 轴的矩形贡献进行编码。 每个矩形在其整个列范围内贡献恒定的高度，因此我们仅存储端点处的更改。 前缀和重建每列的绘制高度。 

最后，在压缩后以 O(1) 的时间查询每个移除的列，并从总面积中减去其贡献。 

一个常见的错误是尝试仅减去已删除列的宽度，而不考虑每个矩形的高度贡献。 这会少算或多算，具体取决于矩形跨行的方式。

 ## 边缘情况

 一种微妙的情况是删除的列不显示为矩形边界。 压缩步骤仍然包含它，因此它会获得有效的索引，并根据覆盖范围贡献零或正值。 该算法可以正确处理此问题，因为它从不假设删除的列与矩形边缘重合。 

另一种情况是宽度为 1 的矩形。这里，差异数组仍然有效，因为每个这样的矩形仅在单个压缩索引上起作用，并且前缀和正确地定位了其效果。 例如，一个矩形$(c, c)$只为该确切的列提供高度。 

第三种情况是许多矩形在 x 投影中重叠，但在 2D 中保持不相交。 该算法在没有干扰的情况下对每列的高度进行求和，并且由于不相交仅适用于 2D，因此这种聚合对于按列计数仍然是正确的。
