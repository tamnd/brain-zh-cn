 ## 解决方案
 ## 问题理解

 我们得到了阿尔贝托严格按顺序消耗的一系列能源。 每个来源都会贡献固定数量的能量，一旦消耗就无法重新访问或分割。 每完成一组训练后，阿尔贝托的能量都会完全重置为零。 

训练组由不断增长的需求定义：第一个俯卧撑消耗 1 能量，第二个俯卧撑消耗 2 能量，依此类推，直到第 M 个俯卧撑消耗 M 能量。 完成一组意味着阿尔贝托必须在连续消耗的摇晃中积累足够的能量，以覆盖总成本 1 + 2 + ... + M。当一组完成时，他不会重新启动摇晃序列，只是重置他的能量计数器。 

这个过程是连续的：他一张一张地消耗奶昔，积累能量，并尝试在奶昔用完之前完成尽可能多的全套。 任务是计算他完成了多少组完整比赛。 

这些约束意味着 O(N) 或 O(N log N) 解决方案。 N 可以达到 100,000，因此对所有集合进行任何二次模拟或重复扫描先前状态都会太慢。 M 至多为 1000，这表明每组要求是有界的，可以预先计算或视为常数阈值。 

如果能量在多次小震动中缓慢积累，或者一次大震动超出了多次俯卧撑要求，则简单的模拟可能会失败。 

例如，如果 M 很小但 N 很大：
 输入：```
5 3
1 1 1 1 100
```粗心的方法可能会尝试单独模拟俯卧撑并重复重新计算要求，如果能量溢出处理不当，则会导致效率低下或重置处理不正确。 

另一个微妙的情况是当单次震动超过多个设定阈值时。 逻辑必须确保多余的能量不会错误地跨过集合。 

## 方法

 直接的暴力解释是完全按照所描述的方式模拟该过程。 我们保持跑步能量值。 我们还模拟当前组：对于从 1 到 M 的每个俯卧撑 i，我们检查当前能量是否足够； 如果没有，我们就会喝更多的奶昔，直到达到为止。 一旦我们完成 M 个俯卧撑，我们就会增加答案并重置能量。 

这种方法是正确的，因为它准确地反映了该过程。 然而，效率低下的原因是重复扫描俯卧撑，并且可能会在组中多次扫描震动。 在最坏的情况下，每次摇动都会通过 M 个步骤进行频繁的内部检查，从而导致 O(NM) 复杂度，可以达到 10^8 次操作。 根据常量，这在 Python 中是临界值或太慢。 

关键的观察结果是，在单个集合中，所需的总能量是固定的并且提前已知：\[
S = 1 + 2 + \dots + M = \frac{M(M+1)}{2}
\]因此，我们不必一一模拟俯卧撑，而只需跟踪累积的能量是否达到 S。每次摇晃都会直接对该累加器做出贡献。 一旦达到或超过 S，我们就完成一组，递增计数器，然后减去 S（这实际上是重置，因为能量不会跨组传递）。 

这将问题简化为简单的线性扫描，维护累积和并计算我们跨越阈值的次数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 暴力模拟| O(NM) | O(1) | O(1) | 太慢了|
 | 每组前缀累积 | O(N) | O(1) | O(1) | 已接受 |

 ## 算法演练

 ### 关键思想
 每组需要固定的能量S。我们只跟踪消耗奶昔时运行总量达到S的次数。 

### 步骤

 1. 计算一套全套所需的总能量：S = M(M+1)/2。 这将变量上推过程转换为单个阈值检查。 
2. 初始化可变电流 = 0，为正在进行的设置存储累积能量。 
3. 初始化答案 = 0 以计算完成的组数。 
4. 按顺序迭代每个能量震动 Ei。 
5. 将 Ei 添加到电流中。 
6. 当当前大于或等于 S 时，从当前中减去 S 并增加答案。 
7.处理完所有抖动后，输出答案。 

减法步骤相当于完成一组并重置能量，除了我们保留当前震动中的剩余能量，这在单个大 Ei 跨越多个组时很重要。 

### 为什么它有效

 一组俯卧撑的过程仅取决于总能量，而不取决于摇动的分布。 由于能源仅用于满足不断增长的需求，因此每套的总成本是固定的。 因此，仅根据固定阈值跟踪累积能量即可完全捕获设置完成情况。 完成一组后的任何多余能量都必须属于下一组，并且减去 S 可以准确保留该剩余状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    E = list(map(int, input().split()))

    S = M * (M + 1) // 2

    current = 0
    ans = 0

    for x in E:
        current += x
        if current >= S:
            ans += current // S
            current %= S

    print(ans)

if __name__ == "__main__":
    solve()
```实施直接遵循阈值降低。 最微妙的选择是使用整数除法来计算一步完成了多少个完整集合。 这是有效的，因为一旦能量超过S，可以立即完成多组全套，剩余的继续进行。 

模运算确保剩余能量被正确保留用于下一组。 这避免了重复循环减法运算并使解保持线性。

 ## 边缘情况

 一个关键的边缘情况是单次能量震动同时完成多组。 例如：

 输入：```
1 3
100
```这里 S = 6。算法计算 current = 100，然后执行 ans += 100 // 6 = 16，余数为 4。 

一步一步地，这符合现实：Alberto 完成了 16 个完整组，并将 4 个能量带入下一个不完整组。 每次迭代仅检查一组完成情况的简单模拟会在第一次完成后错误地停止并丢失剩余能量，从而低估答案。 

另一个边缘情况是没有完成任何一组：

 输入：```
5 4
1 1 1 1 1
```S = 10。运行总数永远不会达到 10，因此 ans 保持为 0。该算法自然地保留当前能量，而不会强制执行不正确的重置，从而符合预期行为。
