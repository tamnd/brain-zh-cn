 ## 解决方案
 ## 问题理解

 我们有一群朋友，每个人都想要一块至少达到一定最小尺寸的布朗尼蛋糕。 我们还得到了一系列烘焙罐，每个罐正好生产一个固定尺寸的布朗尼蛋糕。 每个罐子最多可以使用一次，每个朋友最多可以获得一个布朗尼蛋糕。 如果朋友收到的布朗尼蛋糕严格大于他们要求的尺寸，他就会感到满意。 

任务是以最大化满意朋友数量的方式将罐子与朋友匹配。 

输入由两个数组组成。 第一个描述了每个朋友可接受的最小布朗尼蛋糕尺寸。 第二个描述了罐头生产的可用布朗尼尺寸。 输出是一个整数：有效配对的最大数量，其中锡大小严格大于朋友的要求。 

两个数组中的约束最多为 200,000 个元素。 任何在最坏情况下是二次的解决方案都需要大约 4 × 10^10 的比较，这远远超出了 Python 中两秒内可以执行的范围。 这立即排除了强力配对或检查每个可能的分配。 

问题的一个微妙点是严格的不平等条件。 一罐完全符合要求的尺寸并不能满足朋友的要求。 这改变了我们搜索匹配的方式，因为相等是不可接受的，并且在匹配过程中必须小心跳过。 

第二个微妙的问题是最优分配在本地并不明显。 为小请求提供大罐有时可能会阻碍未来更好的匹配，因此必须仔细证明贪婪的选择的合理性。 

## 方法

 强力解释是考虑将罐子分配给朋友的每一种可能的分配方式并选择最佳匹配。 即使限制我们自己去尝试每个朋友与每个锡罐的比较，也会产生 N × M 的比较。 当两者都达到 2 × 10^5 时，这变得不可行。 

另一种稍微改进但仍然太慢的方法是对两个数组进行排序，并为每个朋友在tins数组中向前扫描以找到第一个有效的tin。 即使进行排序，当许多罐太小时，嵌套扫描仍然会降级为二次行为，因为每个罐可能会被检查多次。 

关键的观察是两个数组都是独立的大小集，我们只关心在单调条件下匹配它们。 一旦排序，结构就变成线性的：如果我们处理最小的未满足的要求，并总是尝试用仍然有效的最小可能的罐子来满足它，我们就可以避免浪费大罐子。 

这自然会导致贪婪策略：对两个数组进行排序并用两个指针遍历它们。 我们尝试将最小的剩余需求与能够满足它的最小锡配对。 如果罐子太小，我们就会丢弃它并继续前进，因为它无法帮助我们尚未达到的任何更大的要求。 如果它足够大，我们匹配它们并推进两个指针。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力配对 | O(NM) | O(1) | O(1) | 太慢了|
 | 排序+贪心二指针| O(N log N + M log M) | O(N log N + M log M) | O(1) 额外 | 已接受 |

 ## 算法演练

 我们按升序对朋友要求和锡尺寸进行排序。 这使问题保持​​一致，以便我们始终首先处理剩余的最小未满足的需求。 

我们维护两个索引，一个用于朋友，一个用于罐头，我们还维护一个成功匹配的计数器。

1、对好友需求数组进行升序排序，对罐尺寸数组进行升序排序。 这确保了我们可以从最小到最大贪婪地推理，而不会错过最佳配对。 
2. 初始化两个指针，i代表friends，j代表tins，都从0开始。同时初始化一个与0匹配的变量。指针i代表最小的未满足需求，j代表最小的未使用的tin。 
3. 当两个指针都在界限内时，比较 s[i] 和 t[j]。 如果 t[j] 大于 s[i]，我们将这个tin分配给这个朋友，增量匹配1，并将两个指针前进。 这是安全的，因为 t[j] 是可以满足 s[i] 的最小锡，因此任何其他选择只会浪费更大的锡。 
4. 如果 t[j] 小于或等于 s[i]，我们通过增加 j 来丢弃这个tin。 它不能满足现在的朋友，而且由于所有未来的朋友都有相同或更大的要求，它也不能满足他们，所以它永远没有用。 
5. 继续，直到任一阵列耗尽。 匹配的值是满意的好友的最大数量。 

为什么它有效可以归结为对排序数组的支配性争论。 在任何步骤中，将最小的不满意的朋友与尽可能最小的可用锡配对可以保留未来的灵活性。 如果我们使用更大的罐子，我们只会减少可用于以后更大需求的选项数量，而不会改善当前的匹配。 该算法保持了这样的不变性：j之前的所有tin要么被使用，要么太小而无用，并且i之前的所有朋友都已经满意。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    s = list(map(int, input().split()))
    t = list(map(int, input().split()))
    
    s.sort()
    t.sort()
    
    i = j = 0
    matched = 0
    
    while i < n and j < m:
        if t[j] > s[i]:
            matched += 1
            i += 1
            j += 1
        else:
            j += 1
    
    print(matched)

if __name__ == "__main__":
    solve()
```实现的核心是排序后的两指针扫描。 排序是必要的，因为贪婪决策仅在两个序列都是单调时才成立。 如果没有排序，局部决策就没有全局保证。 

严格不等式直接在比较中处理`t[j] > s[i]`。 使用`>=`这里会错误地将相同大小的罐子视为有效，这违反了问题条件。 

指针以受控方式前进：i 仅在朋友满意时才移动，j 始终向前移动并且不会再次访问罐子，确保排序后线性扫描。

```排序：

该痕迹表明，小罐头被安全地丢弃，即使它们后来看起来可用，因为存在仍然保持可行性的更大要求。

 ## 边缘情况

 一个关键的边缘情况是许多罐子完全符合要求。 例如：

 输入：```
3 3
5 5 5
5 6 7
```排序后，算法首先将 5 与 5 进行比较。 由于条件很严格，因此它丢弃了罐子。 如此重复直到达到 6，仅产生两场比赛。 一个有缺陷的实现，使用`>=`而不是`>`会错误地计算第一对并返回 3，违反了问题约束。 

当所有罐子都小于所有要求时，会出现另一种边缘情况：```
3 3
10 20 30
1 2 3
```罐头上的指针向前移动，直到耗尽而没有任何火柴。 该算法正确地返回 0，因为没有锡满足严格的不等式条件，并且排序后每次丢弃都通过单调性来证明是合理的。
