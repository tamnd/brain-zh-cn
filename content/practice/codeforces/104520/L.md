 ## 解决方案
 ## 问题理解

 我们得到一棵有根树，其中每个节点都以初始颜色开始，并且必须以目标颜色结束。 唯一允许的操作是选择一个节点并用单一选定的颜色绘制其整个子树。 该操作具有固定成本，具体取决于所选节点，并且它完全覆盖该子树中先前存在的任何颜色。 

关键的困难在于每次绘制都会影响整个子树，而不仅仅是单个节点。 因此，祖先的单个决策可以同时修复或破坏其下面的许多节点，并且更深节点中的后续决策可以覆盖早期的决策。 

输出要求所需操作的最小总成本，以便在所有子树绘制操作之后，每个节点最终都获得其所需的最终颜色。 

这些约束足够大，任何尝试模拟绘画操作序列或枚举每个节点选择的解决方案都会失败。 由于测试用例中的节点多达几百万个，因此解决方案的输入总大小必须接近线性。 任何涉及跨状态的每个节点重新计算或子树信息的二次合并的事情都会立即变得太慢。 

当初始颜色已经与目标颜色匹配时，会出现微妙的边缘情况。 一个幼稚的解决方案可能假设不需要任何操作，但只有当我们能够避免由于子树交互而“强制”不必要的重绘链时，这才是正确的。 另一个边缘情况是，高节点上的廉价绘画操作很诱人，但实际上破坏了正确性，因为它覆盖了稍后需要多种不同颜色的子树。 

例如，考虑一个由三个节点组成的链，其中每个节点需要不同的最终颜色，并且成本沿着链不断下降。 总是首先在最便宜的节点上绘制的贪婪策略会失败，因为早期的绘制操作会破坏精心放置的更深层次的修复。 正确的解决方案必须考虑结构而不是本地成本。 

## 方法

 强力解释是将每个节点视为可能使用也可能不使用的潜在操作，并且对于所选节点的每个子集模拟结果着色。 每个选定的节点都会将颜色应用于其整个子树，并且我们需要通过沿其路径应用最后一个操作来计算每个节点的最终颜色。 这会立即使节点数量呈指数增长，因为每个节点都可以被选择或不被选择，并且由于子树重叠，交互是高度非局部的。 

关键的观察结果是该过程是分层的。 一旦节点被绘制，它就会对其整个子树施加统一的颜色约束，直到某些更深层次的操作覆盖它。 这意味着沿着任何根到叶路径，最终颜色由执行影响该路径的绘制操作的最近选择的祖先确定。 

这将问题转化为管理“颜色权威”如何在树上传递。 在任何节点，我们要么从祖先继承有效的颜色，要么必须创建一个新的绘画操作来纠正不匹配。 树的结构确保可以使用深度优先遍历和干净地向上聚合的本地决策来做出决策。 

我们不跟踪完整的颜色值作为状态，而是只关心当前继承的颜色是否与节点的目标颜色匹配。 这极大地压缩了状态空间，并允许每个节点有两种状态的动态规划公式。

 ## 算法演练

 我们以节点 1 为树根并执行 DFS。 对于每个节点，我们维护两个值：

dp[u][1] 是修复 u 的子树所需的最小成本，假设当前来自其父级的颜色已经与 b[u] 匹配。 

dp[u][0] 是假设父节点的颜色与 b[u] 不匹配时所需的最小成本，这意味着节点 u 当前是“错误的”，必须在其子树内的某个位置进行修复。 

过渡是围绕我们决定在 u 处开始绘画操作还是推迟固定到更深的节点而构建的。 

1. 在后序 DFS 中计算 dp，以便子项在其父项之前得到解决。 
2、在节点u处，首先考虑父颜色与b[u]匹配的情况。 在这种情况下，我们可以对 u 不执行任何操作，只需将相同的正确颜色传播给子级即可。 然后，每个子 v 在状态 dp[v][1] 下求解，因为继承的颜色沿路径保持一致，除非更改更深。 
3.还是在匹配的情况下，我们也考虑在u处进行绘画。 如果我们在 u 处绘画，我们支付 c[u] 并在整个子树上强制使用颜色 b[u]。 此后，每个孩子再次处于相对于 b[u] 的“匹配”状态，因此他们的贡献仍然是 dp[v][1]。 这会在跳过 u 或在 u 处强制执行新重置之间做出选择。 
4. 在不匹配的情况下dp[u][0]，节点u当前没有正确的继承颜色。 这意味着在其子树内部的某个地方，我们必须引入一个绘制操作，为包含 u 的区域中的所有节点建立 b[u]。 
5. 处理 dp[u][0] 的最佳方式是考虑要么从 u 本身开始校正，支付 c[u]，然后求解匹配状态下的子树，要么将第一个校正更深入地推入恰好一个子子树，这有效地将责任向下转移。 这会导致递归，其中 dp[u][0] 是在 u 处绘制和将第一次更正委托给子级之间的最小值。 
6. 计算完两个状态后，dp[1][1] 给出最终答案，因为根没有父约束，并且被认为在顶部已经不匹配。 

关键的不变量是 dp[u][1] 正确地表示一个子树，其中传入的颜色已经满足该子树的根约束，因此 u 不需要强制校正，而 dp[u][0] 表示一种状态，其中必须在子树中引入至少一个校正才能使 u 有效。 由于每个根到节点路径在第一次不匹配时恰好穿过从“正确继承颜色”到“错误继承颜色”的一次转换，因此这两种状态足以对所有有效配置进行编码，而无需跟踪实际颜色。 

这是有效的，因为子树绘制操作仅沿着路径创建均匀颜色的片段。 一旦我们将问题简化为决定这些片段从哪里开始，除了过渡边界之外，全颜色标识就变得无关紧要。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        parent = [0] * n
        if n > 1:
            arr = list(map(int, input().split()))
            for i in range(n - 1):
                parent[i + 1] = arr[i] - 1

        c = list(map(int, input().split()))
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        g = [[] for _ in range(n)]
        for i in range(1, n):
            g[parent[i]].append(i)

        dp0 = [0] * n
        dp1 = [0] * n

        def dfs(u):
            # base contributions
            sum0 = 0
            sum1 = 0

            for v in g[u]:
                dfs(v)
                sum1 += dp1[v]
                sum0 += dp0[v]

            # if parent matches b[u]
            # we can either not paint u or paint u
            cost_if_skip = sum1
            cost_if_paint = c[u] + sum1
            dp1[u] = min(cost_if_skip, cost_if_paint)

            # if parent mismatch, we must "create" a correct segment somewhere in subtree
            dp0[u] = min(cost_if_paint, sum0)

        dfs(0)
        print(dp0[0])

if __name__ == "__main__":
    solve()
```该解决方案根据父指针构建树并运行后序 DFS。 DP 数组存储每个节点的两个概念状态。 对于每个节点，我们首先聚合子节点的贡献，以便我们可以决定是在节点上启动绘画操作还是将工作推迟到子节点更好。 

重要的实现细节是 dp1 仅使用子树的 dp1，因为当传入的颜色已经正确时，子树将保持一致的状态，除非我们显式引入新操作。 dp0 状态结合了在节点本身引入校正或将校正推送到子子树中，这由 dp0 的总和捕获。 

递归深度可以达到树的大小，因此必须增加递归限制。 使用邻接表可确保线性遍历所有节点。 

## 工作示例

 考虑一棵小树，其中节点 1 是根节点并有两个子节点，并且所有节点都需要不同的最终颜色。 假设成本是这样的：画根部很便宜，但画孩子很昂贵。 DP 会将叶子处的 dp1 评估为不执行任何操作或支付叶子成本，并且 dp0 将强制进行修正，最终选择最便宜的位置来引入第一个有效段。 

| 节点| dp1（父匹配）| dp0（父级不匹配）|
 | --- | --- | --- |
 | 叶| 分钟（0，c）| 分钟（c，0）|
 | 内部| 结合子 dp1 | 分钟（在这里绘制，向下推）|

 此跟踪显示 dp1 如何自然地向下传播一致性，而 dp0 强制子树中的某处至少存在一个更正。 

现在考虑一个由三个节点组成的链。 如果根不匹配，则 dp0 强制在根处绘制或将更正推送到节点 2 或节点 3。递归确保仅最便宜的有效放置幸存，因为所有替代方案都是通过 dp0 聚合显式比较的。

 ## 边缘情况

 关键的边缘情况是初始颜色已与目标匹配但其子节点需要不同颜色的节点。 该算法可以正确处理此问题，因为 dp1 允许跳过该节点上的任何操作，同时仍然强制向子节点强制传播。 

另一种情况是，在父级上绘画似乎是全局最优的，但实际上阻塞了子树中所需的结构。 DP 通过始终比较“在这里绘制”与“向下推送决策”来避免这种情况，确保只有在同时改进所有受影响的子树时才会采取高成本的早期决策。 

最后一种情况是长链退化树。 这里，dp0状态确保算法不会错误地无限期地推迟所有校正； 它精确地强制引入有效颜色段的一个过渡点，并在线性时间内评估该过渡的所有可能位置。
