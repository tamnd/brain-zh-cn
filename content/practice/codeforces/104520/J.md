 ## 解决方案
 ## 问题理解

 我们有一个循环时间表$N$天，其中会议在每个周期的某些天数中举行。 每个$M$问题设置者有固定的每周模式：设置者$i$出席会议$p_i$周期的特定天数。 

现在想象一下有一天出现一个想法$d$。 从那一刻起，只有当两个人在同一次会议上相遇时，信息才会传播。 老板是唯一可以积极参加会议以“传播”信息的人。 每当他在某一天参加会议时，出席该会议的所有设置者都会意识到，并且他们可以以同样的方式进一步将意识传播到他们参加的其他会议。 

我们必须保证在接下来的时间内$N$从一天开始的天数$d$，每次召开的会议都必须是“富有成效的”，这意味着至少有一名与会者要么是老板本人，要么是已经意识到这个想法的人。 任务是计算每个开始日$d$，为确保这一条件，Bossographer 必须参加的最少会议次数。 

重新构建这一点的一个有用方法是将日期视为图表中的节点，每个设置者将他们参与的所有日期连接成一条“潜在信息传输”链。 如果 Bosslogger 进入任何一天，他会激活通过共享设置器链接的日期的整个连接组件，但仅通过他实际访问的会议来激活。 目标是找到他必须直接“注入”意识的最小天数，以便在接下来的时间内可以到达所有相关的天数$N$循环窗口被覆盖。 

限制条件很大：$N, M \le 10^5$和总出席人数高达$5 \cdot 10^5$。 这排除了任何在所有 setter 上使用 BFS 或 DFS 为每个开始日独立重新计算可达性的解决方案，因为这会导致粗略的结果$O(N \cdot (N + M))$最坏情况下的行为，远远超出了限制。 

一个关键的微妙之处在于，每个起始日都需要独立的答案，并且循环结构意味着每个查询对应于一个长度的滑动窗口$N$在圆形排列上。 这种循环依赖是简单重新计算失败的地方。 

一个重要的边缘情况是一天根本没有会议。 那一天对答案没有贡献，但它仍然影响天循环中的邻接。 粗心的解决方案可能会错误地将其视为不相关并破坏连续性，从而导致错误的组件合并。 

另一种微妙的情况是所有设置者只参加同一天。 那么当天 Bossographer 的一次出席应该会激活所有内容，但如果实现独立对待每个 setter，它可能会错误地假设需要多个种子。 

## 方法

 蛮力方法试图独立模拟每个开始日的过程。 对于固定的日子$d$，我们考虑下一个$N$天并构建一个图表，如果某个设置者同时参加了这两个天，那么天就被连接起来。 然后我们重复模拟传播：如果 Bosslogger 参加了一天，所有通过 setter 连接的日子都会被激活，并且这种情况会持续下去，直到不可能再有增长为止。 最小会议次数成为覆盖该窗口中所有活动组件所需的最小种子天数。 

从概念上讲，这是可行的，因为意识传播正是对共享出席的传递性封闭，但成本却令人望而却步。 对于每个开始日，构建归纳图的成本$O(N + \sum p_i)$，并且运行传播的成本类似。 为所有人做这件事$N$起点大致给出$O(N^2)$实践中的行为，对于$N = 10^5$。 

关键的洞察力是颠倒视角。 我们观察到每个设置者有效地定义了他们参加的日期之间的连接，而不是模拟每个开始日的传播，并且这些连接不依赖于开始日。 唯一改变的是$d$是在大小的滑动窗口中被视为活跃的天子集$N$。 

因此，问题变成了固定二分结构（setter 和 days）上的滑动窗口连接问题。 每个设置者在其参与的日子中贡献边缘，我们想知道有多少个连接的组件与每个循环窗口相交。 窗口的答案本质上是 Bossographer 必须“接触”的组件数量，这减少为计算有多少组件没有被先前的种子内部激活。 

这导致了几天内的不相交集结构，在全局范围内构建一次。 之后，每个查询都减少为对循环数组上的某个范围内的组件进行计数，这可以通过预处理和前缀技术来处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(N(N + M))$|$O(N + M)$| 太慢了|
 | 最佳|$O((N + M) \alpha(N))$|$O(N + M)$| 已接受 |

 ## 算法演练

 1. 建立一个联合查找结构$N$天。 对于每个二传手，他们参加的所有日子都与他们名单中的代表日结合在一起。 这将每个二传手的影响力压缩成一个相互关联的日子。 
2. 处理完所有 setter 后，每一天都属于一个组件，代表通过共享 setter 相互连接的所有日期。 这是不依赖于查询开始的全局传播结构。 
3. 构造数组`comp[d]`将每天映射到其组件标识符。 这将问题转化为处理圆形阵列上组件 ID 的线性序列。 
4. 每一天$d$，我们想知道循环间隔中出现了多少个不同的分量$[d, d+N-1]$。 因为结构是圆形的，所以这个间隔对应于取数组两次并滑动一个长度的窗口$N$。 
5. 构建双倍数组`A`长度$2N$， 在哪里`A[i] = comp[(i mod N)]`。 这种线性化允许每个循环窗口成为标准的连续子阵列。 
6. 计算每个长度窗口中不同分量的数量$N$使用滑动窗口频率图。 维护窗口中当前存在的组件数量的计数器。 
7. 对于每个位置$d$，答案是窗口中从以下位置开始的不同组件的数量$d$。 这代表存在多少个互不相连的“信息区域”，每个区域都需要至少一名 Bossographer 直接出席才能激活。 

### 为什么它有效

 每个设置者都会在他们参加的日子中创建对等性，这意味着信息始终可以在相连的几天内自由移动，而无需 Bossographer 进行额外的努力。 因此，一旦形成全局连通组件，Boss导唯一剩下的任务就是确保在时间窗口中出现的每个组件至少被激活一次。 由于组件中一次会议的激活会扩展到其所有日子，因此他必须参加的最小会议数量恰好是该窗口中存在的不同组件的数量。 联合查找结构确保这些组件在相互可达性下最大化，因此不再依赖于查询开始进行进一步的拆分或合并。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    N, M = map(int, input().split())
    dsu = DSU(N)

    day_sets = []

    for _ in range(M):
        arr = list(map(int, input().split()))
        p = arr[0]
        days = [x - 1 for x in arr[1:]]
        if p == 0:
            continue
        first = days[0]
        for d in days[1:]:
            dsu.union(first, d)

    comp = [dsu.find(i) for i in range(N)]

    A = comp * 2

    freq = {}
    distinct = 0
    ans = [0] * N

    l = 0
    for r in range(2 * N):
        c = A[r]
        freq[c] = freq.get(c, 0) + 1
        if freq[c] == 1:
            distinct += 1

        if r - l + 1 > N:
            left_c = A[l]
            freq[left_c] -= 1
            if freq[left_c] == 0:
                distinct -= 1
                del freq[left_c]
            l += 1

        if r >= N - 1:
            start = r - N + 1
            if start < N:
                ans[start] = distinct

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```DSU 结构使用每个二传手的出勤列表将天数合并到全球可达性组件中。 压缩步骤确保每个组件的行为就像一个原子单元。 

双倍数组是处理循环间隔而不需要模运算复杂性的标准技巧。 滑动窗口维护每个间隔中活动组件的精确计数，并且字典跟踪多重性，因此我们可以维护每个间隔中不同组件的数量。$O(1)$每一步摊销。 

一个微妙的点是条件`r >= N - 1`，这确保我们只在整个窗口大小后才开始记录答案$N$已经形成。 如果没有这个，部分窗口将错误地影响结果。

 ## 边缘情况

 一种边缘情况是根本没有设置者。 在这种情况下，每天都会形成自己的组成部分，因此每个窗口都包含$N$不同的组成部分，Boss导必须参加窗口中的每一次会议。 DSU 从来不联合任何东西，所以`comp[i] = i`，并且滑动窗口正确计算所有不同的 ID。 

另一种情况是二传手全天都在场。 这会将整个 DSU 折叠成单个组件。 滑动窗口总是准确地看到一个组成部分，因此每天的答案都变为 1，这与一次出席在全球范围内传播的直觉相匹配。 

更微妙的情况是，出勤模式形成一条链，例如二传 1 连接第 1-2 天，二传 2 连接 2-3 天，依此类推。 DSU 逐渐将所有内容合并到一个组件中，尽管没有任何一个 setter 能够全天候工作。 正确性来自联合体的传递性，它与重叠会议上的真实信息流相匹配。
