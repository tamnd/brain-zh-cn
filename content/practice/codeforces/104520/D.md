 ## 解决方案
 ## 问题理解

 每个查询描述了一系列整数`l`到`r`，并询问有多少个有序对`(a, b)`在该范围内满足涉及函数的特定条件`f(a, b)`。 在我们开始计算对之前，函数本身就已经简化了。 

表达式`f(a, b) = a + b + |a - b|`行为有所不同，具体取决于哪一个`a`和`b`更大。 如果`a ≤ b`， 然后`|a - b| = b - a`，因此表达式变为`a + b + (b - a) = 2b`。 如果`a > b`， 然后`|a - b| = a - b`，因此表达式变为`a + b + (a - b) = 2a`。 由于问题限制了我们`a ≤ b`，只有第一种情况很重要，并且函数总是简化为`f(a, b) = 2b`。 

这会立即改变每个查询的解释。 我们不是考虑成对的，而是真正计算有多少种选择`(a, b)`和`l ≤ a ≤ b ≤ r`满足`2b = x`。 一次`b`是固定的，`a`可以是任意整数`l`到`b`。 

约束非常大，值高达`10^18`直至`2 × 10^5`查询。 任何迭代范围或枚举对的解决方案都是不可能的。 即使每个查询迭代单个范围也已经太慢了。 

当出现微妙的边缘情况时`x`很奇怪。 自从`2b = x`，没有整数`b`存在，所以答案一定是零。 当隐含的情况发生时，会出现另一种边缘情况`b = x / 2`位于外面`[l, r]`，其结果也为零。 

## 方法

 蛮力方法将迭代所有对`(a, b)`对于每个查询，检查是否`l ≤ a ≤ b ≤ r`以及是否`f(a, b) = x`。 这需要粗略地检查`(r - l + 1)^2 / 2`每个查询对。 自从`r`可以大到`10^18`，这是完全不可行的。 

关键的观察来自于简化功能。 因为`f(a, b)`总是崩溃到`2b`约束下`a ≤ b`，该值仅取决于`b`，不在`a`。 这完全消除了问题的二维结构。 

对于固定查询`(l, r, x)`，我们首先检查是否`x`是均匀的。 如果是奇数，则不存在解。 否则我们设置`b = x / 2`。 现在的条件纯粹是关于是否`b`位于区间内`[l, r]`。 

如果`b`是有效的，我们计算所有可能的`a`这样`l ≤ a ≤ b`。 正好有`b - l + 1`选择。 如果`b < l`或者`b > r`，答案为零。 

这将每个查询减少为常数时间算术。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每个查询 O((r−l)^2) | O(1) | O(1) | 太慢了|
 | 最佳| 每个查询 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读每个查询`(l, r, x)`并判断是否为有效值`b`可以存在。 自从`f(a, b)`简化为`2b`，值`x`必须是均匀的。 如果`x`是奇数，答案立即为零。 
2. 计算`b = x / 2`。 这是该对中较大元素的唯一候选值。 其余的推理完全取决于该值是否位于查询间隔内。 
3. 检查是否`b < l`或者`b > r`。 如果任一条件成立，则不存在有效对，因为所有有效对都需要`l ≤ a ≤ b ≤ r`。 
4. 如果`b`是在`[l, r]`，计算有多少个有效的`a`价值观是存在的。 自从`a`范围从`l`到`b`，包含在内，计数为`b - l + 1`。 
5. 输出该值进行查询。 

### 为什么它有效

 的转变`f(a, b)`将每个有效对折叠到仅取决于该对的第二个元素的条件。 约束条件`a ≤ b`确保函数的计算结果始终为`2b`，使所有对具有相同的`b`就有效性而言是等价的。 因此，计算对就相当于计算有效选择`a`对于每一个可行的`b`，并且导出区间之外的任何对都不能满足方程。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    out = []
    
    for _ in range(q):
        l, r, x = map(int, input().split())
        
        if x % 2 == 1:
            out.append("0")
            continue
        
        b = x // 2
        
        if b < l or b > r:
            out.append("0")
            continue
        
        out.append(str(b - l + 1))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案依赖于将每个查询减少为从方程导出的单个候选值。 奇偶校验防止无效的半值，范围检查确保我们只计算遵守原始间隔约束的对。 算术`b - l + 1`直接计算有效选择`a`无需任何迭代。 

一个常见的实施陷阱是忘记`a`不影响`f(a, b)`一旦订购。 另一个错误地假设两者`a ≤ b`和`b ≤ a`案例分别贡献，这会重复计算或引入不必要的分支。

 ## 边缘情况

 当出现一种边缘情况时`x`很奇怪。 用于输入`(l=1, r=10, x=7)`，算法立即拒绝它，因为`b = x/2`不是整数，产生输出`0`无需进一步检查。 

另一种情况是当`b`位于区间下方。 为了`(l=5, r=10, x=6)`，我们得到`b = 3`，小于`l`，所以没有有效的`a`存在。 该算法正确地停止在范围检查处。 

最终边界情况发生在`b`等于`r`。 为了`(l=3, r=8, x=16)`，我们得到`b = 8`，并且有效`a`值是`3..8`，生产`6`。 公式`b - l + 1`正确包含两个端点而无需调整。
