 ## 解决方案
 ## 问题理解

 我们得到一堆不同的整数，其中第一个元素是底部，最后一个元素是顶部。 我们可以使用这个堆栈的后缀，这意味着我们从顶部删除一些元素，暂时保存它们，仅对那些删除的元素进行排序，然后将它们按排序顺序放回顶部。 堆栈的其余部分保持不变。 

任务是找到必须从顶部弹出的最小数量的元素，以便在对那些弹出的元素进行排序并重新附加它们之后，整个堆栈从下到上按递增顺序排序。 

因此，输出不是最终的堆栈，而是所需的最小后缀长度，以便“弹出、排序、重新插入排序”的单个操作足以使整个结构排序。 

约束足够大，以至于每次测试的 O(n²) 模拟都无法通过。 跨测试用例的 n 总和高达 2 × 10⁵，这强烈表明每个测试解决方案需要 O(n) 或 O(n log n)，总体上最好是线性的。 

一个微妙的点是，我们不允许对堆栈的任意元素进行重新排序，只能对顶部的连续后缀进行重新排序。 这消除了许多试图修复数组中任何位置的局部反转的天真的贪婪策略。 

一些边缘案例暴露了常见的错误。 如果堆栈已经排序，则无需弹出，答案为零。 例如，输入`1 2 3`应该返回 0。总是假设必须移动至少一个元素的天真的方法在这里会失败。 

另一个棘手的情况是几乎所有事情都颠倒过来时，例如`4 3 2 1`。 唯一有效的方法是弹出所有元素，对它们进行排序，然后重新插入，因此答案是 4。任何试图保留中间部分顺序的方法都会低估所需的后缀。 

最后，考虑像这样的混合情况`1 4 2 3`。 尽管大多数元素都接近其最终位置，但后缀约束迫使我们仔细选择排序后缀的开始位置。 正确答案是 3，因为弹出`[4,2,3]`足以修复顺序，而仅弹出最后两个不足以修复涉及 4 的反转。 

## 方法

 一个直接的蛮力想法是尝试从 0 到 n 的每个可能的 k 值。 对于每个 k，我们弹出前 k 个元素，对它们进行排序，然后模拟重新插入它们。 重建后，我们检查整个数组是否已排序。 由于排序，每个模拟的成本为 O(n log n)，并且在最坏的情况下，对所有 k 执行此操作会导致每个测试的 O(n² log n)。 当总 n 达到 2 × 10⁵ 时，这太慢了。 

关键的观察是，我们实际上并没有选择任意元素，而只是选择后缀，并且最终的数组必须是全局排序的。 这意味着保持不变的元素必须已经形成排序数组的前缀，否则无论对后缀进行多少排序都无法修复保留元素之间的不匹配。 

如果我们想象最终的排序数组，那么未触及的部分必须与正确顺序的最小值完全对齐。 这意味着，如果我们从底部扫描并跟踪是否可以将元素保留为已排序排列的有效前缀，那么只有当遇到破坏相对于剩余值所需的递增结构的元素时，我们才会失败。 

这导致重新构建问题：我们希望从底部开始的最长前缀可以保持不变，同时仍然与全局排序的最终数组保持一致。 一旦该前缀被修复，它上面的所有内容都必须被弹出并排序。 

因此，我们不是直接决定 k，而是计算底部可以保留多少个元素，然后从 n 中减去。

 ## 算法演练

 我们使用这样的想法：当按值的顺序考虑时，保留在原处的元素必须形成排序数组的有效前缀。 

1. 对数组的副本进行排序。 这给出了目标值的最终顺序。 我们将使用它作为所有操作后堆栈应该是什么样子的参考。 
2. 构建从值到其在排序数组中的位置的映射。 这告诉我们每个元素的正确排名。 
3. 从下到上扫描原始堆栈，如果我们假装正在构建排序数组的有效前缀，则跟踪迄今为止我们看到的最大排名。 
4. 每当当前元素的排名大于我们在严格一致的前缀中预期的下一个排名时，我们就无法将未触及的前缀扩展到这一点以上。 
5. 从底部算起的最长有效前缀为我们提供了可以保持不变的元素数量。 
6. 答案 k 是不在该前缀中的元素数量，即 n 减去该前缀长度。 

关键思想是，未触及的前缀不得引入任何与排序顺序相关的“未来约束违规”。 一旦某个元素在排序排名进展方面不合适，它上面的所有内容都必须是我们排序的后缀的一部分。 

### 为什么它有效

 堆栈中未触及的部分必须与最终排序数组的最低段完全匹配，因为所有剩余元素都将按排序顺序重新插入到其上方。 如果前缀元素的排名高于前缀中后面的元素，则后缀的重新排列无法修复相对排序约束，因为后缀操作无法将元素移动到保留区域中。 这迫使保留区域恰好是与排序排列下递增的排名顺序一致的最长前缀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        sorted_p = sorted(p)
        pos = {v: i for i, v in enumerate(sorted_p)}

        # longest valid prefix from bottom
        max_rank = -1
        keep = 0

        for x in p:
            r = pos[x]
            if r > max_rank:
                keep += 1
                max_rank = r
            else:
                break

        print(n - keep)

if __name__ == "__main__":
    solve()
```解决方案首先对数组进行排序以定义正确的全局顺序。 字典将每个值映射到其排名，从而允许在扫描期间进行恒定时间比较。 

然后我们从下到上遍历，保持有效前缀中迄今为止看到的最高排名。 如果下一个元素需要比已包含的元素更小的排名，我们将停止扩展前缀。 这直接确定了有多少元素可以保持不变。 结果被计算为该前缀大小的补码。 

一个常见的陷阱是从顶部而不是底部进行扫描，这打破了对固定内容的解释。 堆栈结构使得自下而上的方向至关重要，因为只允许后缀操作。 

## 工作示例

 ### 示例 1

 输入：`1 2 3`| 步骤| 价值| 排名| 最大排名 | 保持|
 | ---| ---| ---| ---| ---|
 | 1 | 1 | 0 | 0 | 1 |
 | 2 | 2 | 1 | 1 | 2 |
 | 3 | 3 | 2 | 2 | 3 |

 所有元素都扩展一个有效的前缀，因此 keep = 3，因此 k = 0。 

这证实了当数组已经排序时，不需要弹出。 

### 示例 2

 输入：`1 4 2 3`| 步骤| 价值| 排名| 最大排名 | 保持|
 | ---| ---| ---| ---| ---|
 | 1 | 1 | 0 | 0 | 1 |
 | 2 | 4 | 3 | 3 | 2 |
 | 3 | 2 | 1 | 3 | 停止|

 在第三个元素处，rank 1 小于 max_rank 3，因此前缀中断。 我们得到 keep = 2，所以 k = 2。 

这演示了相对于排序顺序的单个反转如何停止未触及前缀的扩展，从而强制完全重建剩余的后缀。

 ## 边缘情况

 对于单元素堆栈，算法立即分配 keep = 1，因为只有一个等级并且不会出现矛盾。 输出变为零，与不需要任何操作的事实相匹配。 

对于完全反转的堆栈，例如`5 4 3 2 1`，排序按从 0 到 4 的递增顺序分配排名，但从下到上扫描会立即导致第二个元素的排名下降，从而破坏第一个元素之后的前缀。 这会产生 keep = 1 和 k = 4，正确地要求弹出所有元素。 

对于像这样的情况`1 3 2 4`，扫描接受`1`然后`3`，但拒绝`2`因为它的排名小于当前的最大值。 前缀到此为止，只有两个元素保持固定，k = 2，这符合修复中间反转的需要。
