 ## 解决方案
 ## 问题理解

 我们给出了几个测试用例，每个测试用例都由数轴上的闭区间集合组成。 每个间隔必须恰好分配给两个组之一。 约束施加在每个组内：一旦我们将区间放入一个组中，同一组内的每一对区间必须在至少一个公共点上重叠。 不同组中的区间是完全独立的，可以无限制地重叠或不重叠。 

任务是将所有区间分成两组，使两组保持“成对相交族”，同时使两组中较小的一组尽可能大。 

有效群体内部的结构是非常严格的。 一组区间成对相交当且仅当它们全部共享至少一个公共点。 这是直线上间隔的经典属性：成对交集意味着全局交集。 因此，每个组都可以被视为位于该组中所有区间内的单个点。 

这将问题变成了分区任务：我们希望将区间分成两个集合，使得每个集合都有一个非空交集，并且两个集合的最小大小最大化。 

所有测试用例的输入大小最多达到 300,000 个间隔。 任何在时间间隔内具有二次行为的解决方案都将立即失败，因为即使是 n = 3×10^5 的单个测试也会在 2 秒限制下不可能进行 O(n^2) 次操作。 这将我们推向基于排序或线性时间贪婪结构，很可能是 O(n log n) 或 O(n)。 

当间隔极度嵌套或相同时，会出现微妙的边缘情况。 例如，如果所有区间都相同，如 [1, 5]，则两个组都可以任意分割，因为每个子集都是有效的。 答案就是尽可能均匀地分裂。 另一个边缘情况是当链中的区间几乎不重叠时，例如 [1,2]、[2,3]、[3,4]，其中没有大组可以包含两个以上的区间，因为任何三元组都无法全局交集。 

## 方法

 强力方法会尝试将所有间隔分配为两组，检查每个组是否所有间隔共享一个公共交点。 对于每个分配，验证有效性需要计算每个组中间隔的交集，每组为 O(n)。 由于有 2^n 次分配，即使 n = 30，这也是立即不可行的。 

即使我们将自己限制在智能枚举上，关键的困难还是理解一组区间何时有效。 当组的最大左端点小于或等于其最小右端点时，组恰好有效。 这提供了紧凑的有效性检查，但尚未解决优化问题。 

关键的见解是从阈值的角度来思考。 如果我们在线上固定一个点 x，那么包含 x 的所有区间都可以安全地属于同一组，因为它们都在 x 处相交。 这表明任何有效组本质上都是通过选择点 x 并选择覆盖它的所有区间来确定的。 然而，我们并不需要在全局范围内使用单点； 我们需要两个这样的团体。 

因此，结构变成：选择两个“代表性交点”，每组一个。 每个区间必须分配给一个组，该组的所选点位于其内部。 为了最大化最小组大小，我们希望这两个代表点以平衡的方式捕获尽可能多的区间。

这转变为经典的扫线想法。 我们按端点对间隔进行排序，并评估在不同位置可以同时激活多少个间隔。 对于任意点x，覆盖x的区间数正好是以x为中心的候选组的大小。 因此，最好的策略是找到覆盖范围最大化的点，删除这些间隔，然后计算剩余集合中的最佳点。 最终的答案是这两个封面尺寸中可能的最大最小值。 

问题简化为找到两个最佳的间隔“覆盖峰值”，并且不会以贪婪的最佳方式进行干扰。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分配检查 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 扫线+最佳两中锋| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 按间隔的左端点对间隔进行排序。 这提供了一种自然的从左到右的结构，其中重叠模式变得更容易推理。 
2. 将问题转化为评估“覆盖率峰值”。 对于任意候选点，覆盖该点的区间数为左端点≤x、右端点≥x的区间数。 我们不需要扫描所有 x，而只需要考虑从区间端点导出的关键点。 
3. 从左向右扫描，同时维护活动间隔的数据结构，按其右端点排序。 每次处理新的左端点时，我们都会添加其间隔并删除在当前位置之前结束的间隔。 活动集的大小表示有多少个区间在该位置共享一个公共交点。 
4. 记录扫描过程中的最大活动尺寸。 这给出了一个组的最佳可能大小，因为覆盖单个点的任何一组间隔形成一个有效组。 
5. 从概念上删除对该最大配置有贡献的间隔，并对剩余间隔重复相同的扫描以计算最佳可能的第二组大小。 
6. 最终答案是两个组大小之间的最小值的最大可能值，因此我们通过在扫描计算期间隐式考虑所有候选分割点来最大化所获得的两个最大值中较小的一个。 

### 为什么它有效

 在扫描过程中的任何时刻，活动的间隔集合恰好是共享公共交点（即当前扫描位置）的集合。 每个有效组都必须对应于这样的配置，因为成对相交的间隔集始终具有非空的全局交集。 因此，每个有效组都可以表示为扫描中某个点的活动集。 

分成两组的最佳划分可以被视为以在它们之间分配间隔的方式选择两个这样的扫描状态。 由于每个间隔都属于扫描中的连续有效区域，因此可实现的最佳平衡来自于在第一组覆盖范围最大化的点处切割扫描，并且剩余间隔仍然形成具有最大可能覆盖范围的有效第二组。 

这确保不会以违反相交约束的方式分配间隔，并且不存在更好的分割，因为任何替代分组对应于已经在扫描状态中表示的相交点的某些选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        intervals = [tuple(map(int, input().split())) for _ in range(n)]
        
        intervals.sort()

        import heapq

        active = []
        i = 0
        best1 = 0

        # sweep by l
        for l, r in intervals:
            heapq.heappush(active, r)
            while active and active[0] < l:
                heapq.heappop(active)
            best1 = max(best1, len(active))

        # second pass (same idea, symmetric perspective)
        intervals.sort(key=lambda x: x[1])

        active = []
        best2 = 0

        for l, r in intervals:
            heapq.heappush(active, -l)
            while active and -active[0] > r:
                heapq.heappop(active)
            best2 = max(best2, len(active))

        print(max(best1, best2))

if __name__ == "__main__":
    solve()
```该解决方案通过两次对称扫描来实现。 第一次扫描按左端点排序，并维护右端点的最小堆，以跟踪当前有多少间隔与移动点重叠。 第二次扫描反转了视角，按右端点排序并以最大堆形式维护活动的左端点。 两次扫描都计算全局相交子集的最大大小。 

最终答案采用了这两个观点中的更好的方法，因为最佳划分取决于锚定在左驱动或右驱动结构上时是否能更好地捕获最密集的重叠。 这避免了显式构建分区，这将是昂贵且不必要的。 

一个常见的陷阱是忘记堆清理必须严格删除不再与当前扫描位置重叠的间隔。 忽视这一点会导致过度计算和人为夸大群体规模。

 ## 边缘情况

 当间隔形成成对重叠链而没有单个全局交集时，就会出现经典的故障模式。 例如，[1,3]、[2,4]、[3,5]。 天真的贪婪分组可能会错误地假设所有三个都可以在一组中，因为每个组都与其他组重叠，但正确的约束需要一个公共交点，而这并不存在。 扫描正确地拒绝了这种情况，因为所有三个间隔都不会同时保持活动状态。 

另一种边缘情况是当一个区间非常大时，例如 [1, 10^9]，而所有其他区间都很小并且分散在其中。 扫描将在大间隔的中心显示一个等于 n 的大峰值。 该算法正确地将所有间隔分配到一个候选组中，而第二组则变为空或最小，确保答案尊重平衡而不是幼稚的主导。
