 ## 解决方案
 ## 问题理解

 我们正在按固定顺序处理一系列值。 分数从零开始，对于序列中的每个值，我们必须立即决定是将其添加到当前分数还是将当前分数乘以它。 一旦决定了某个位置，以后就不能更改，我们将继续执行下一个值。 

目标是在处理所有值后最大化最终分数。 

每个测试用例的元素数量限制很小，最多 100 个，但测试用例最多可以有 10,000 个。 这种组合意味着每个测试用例具有二次工作量的任何解决方案都是可以接受的，而任何指数工作量的解决方案都是可以接受的。$N$即使修剪也是不可能的。 

关键的困难在于乘法与符号和大小有强烈的相互作用。 负值可以翻转整个累积结果的符号，而早期的大正值可以极大地放大未来的选择。 根据给定步骤中乘法或加法是否更大来进行局部决策的天真贪婪方法将会失败。 

当早期乘法产生负的中间结果，随后产生非常大的增益时，就会出现一个简单的失败情况：

 输入：```
3
-2 -2 100
```如果我们贪婪地添加早期值并且仅在局部看起来有利时才相乘，我们可能会避免早期乘法并以较小的结果结束，但最佳策略是尽早小心地创建一个较大的值，以便以后的乘法占主导地位。 

另一个微妙的问题是零的行为就像乘法的重置。 乘以零会破坏所有未来的放大潜力，因此任何正确的策略都必须将零视为结构断点。 

## 方法

 暴力解决方案将模拟所有可能的选择序列。 在每个位置我们要么加要么乘，给出$2^N$每个测试用例的可能性。 为了$N = 100$，这是完全不可行的，因为即使$2^{30}$已经超过十亿个状态，我们还需要保持中间整数增长。 

问题的结构表明了动态规划的公式。 在每个索引中，我们都为所有可能的计算“状态”维护可达到的最佳分数。 然而，状态空间不仅仅是索引，它是当前值，这使得由于无界增长而无法实现简单的 DP 超过值。 

关键的观察结果是，分数是根据输入序列构建的线性表达式，但动态选择每个术语是成为产品链的一部分还是简单地添加。 任何最佳策略都可以解释为将数组分成段，在段内我们有效地选择乘法链，在段之间我们通过加法重置。 

更具体地说，如果我们确定一个选择加法的点，那么就乘法相互作用而言，它之前的所有内容都与其之后的所有内容无关。 这表明我们可以在跟踪以“乘法链”结束与以“闭合加法状态”结束的最佳结果的位置上维持 DP。 

在每一步中，我们都有两种有意义的解释：

 我们要么通过乘以下一个值来扩展正在运行的乘法链，要么打破链并将当前贡献添加到最终结果中，从而重置链状态。 

这将问题简化为每个位置的状态数恒定。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（所有选择）| O(2^N) | O(2^N) | O(N) | 太慢了|
 | 具有链状态的 DP | O(N) | O(1) | O(1) | 已接受 |

 ## 算法演练

 从左到右扫描数组时，我们维护两个值。 

如果我们已经将所有先前的贡献“提交”到最终总和中，则一个值代表最佳分数。 另一个代表尚未最终确定答案的活动乘法链的最佳值。 

我们还跟踪是否已经启动了一个链，因为初始化之前的乘法与初始化之后的乘法的行为不同。 

### 步骤

 1. 初始化一个 DP 状态，其中最佳最终得分为零且没有活动链。 
2. 对于每个值$a_i$，考虑两个操作：启动或扩展乘法链，或最终确定链并添加当前贡献。 
3. 当在位置启动链条时$i$，我们将链值设置为$a_i$或当前链中的产品（如果存在）。 
4. 当延伸一条链时，我们通过乘以来更新链值$a_i$。 这体现了我们正在构建一个连续的乘法块的想法。 
5. 在每个位置，我们还考虑打破链条：我们将当前链条值添加到最终得分中并重置链条。 
6. 答案是最终得分的最大值以及我们通过关闭最后一条链来结束的情况。 

### 为什么它有效

 不变的是处理后的位置$i$，DP 正确地表示了将前缀划分为乘法链和最终加法的交替段的所有最佳方式。 任何最佳解决方案都可以分解为这样的片段，因为每个乘法决策在连续区域内都是关联的，并且打破该区域相当于在该边界处选择加法。 由于 DP 隐式地保留每个有效分割模式的最佳可能结果，因此不会错过任何最佳结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(a):
    n = len(a)
    
    # dp0: best finalized score so far
    # dp1: best value of active multiplication chain
    dp0 = 0
    dp1 = None  # no chain yet
    
    for x in a:
        new_dp0 = dp0
        
        # Option 1: extend or start chain
        if dp1 is None:
            new_dp1 = x
        else:
            new_dp1 = dp1 * x
        
        # Option 2: break chain and add it to result
        if dp1 is not None:
            new_dp0 = max(new_dp0, dp0 + dp1)
        
        # Option 3: start new chain at current position
        new_dp1 = max(new_dp1, x)
        
        dp0, dp1 = new_dp0, new_dp1
    
    if dp1 is not None:
        dp0 = max(dp0, dp0 + dp1)
    
    return dp0

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        out.append(str(solve_case(a)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该代码维护两个不断变化的量。`dp0`代表所有先前操作已最终确定为加法的最佳分数。`dp1`表示当前活动的乘法链，以后可能仍会扩展或关闭。 

在每一步中，我们要么扩展乘法链，要么在当前元素处重新启动它。 我们还可以选择关闭链条并将其添加到最终得分中。 谨慎的部分是确保我们在考虑继续和关闭链之前不会过早地丢弃该链，这就是为什么两个转换都是在分配之前计算的。

 ## 边缘情况

 单元素数组很简单，因为从零开始时，加法和乘法都会产生相同的值。 DP 正确初始化链并立即返回该值。 

全零数组迫使每个乘法链崩溃，并且该算法通过重复重新启动链正确地避免创建负或不稳定的结构。 

全负数组是最微妙的情况，因为乘法会交替符号。 DP 不断延伸链条，因为中间的负面影响不会立即提交，只有在有利时才会关闭，最终捕获完整的产品。 

混合符号数组如`10 -1 10`证明为什么贪婪会失败。 该算法首先构建一条链，翻转一次符号，然后正确地重新启动以最大化第二个乘法段，从而产生更大的最终分数。
