 ## 解决方案
 ## 问题理解

 我们在平面上得到一组点，每个点都带有一个正值，被解释为油量。 Alice 可以选择这些点的一些子集并在它们周围绘制闭合边界。 边界就像栅栏：其内部或之上的所有东西都被认为是安全的，并将其石油价值贡献给利润。 

建造此围栏的成本取决于其几何周长。 如果周长是$k$，成本是线性函数$m \cdot k + c$。 最终的利润就是围栏内的石油总量减去这个建设成本。 任务是选择点的子集和围栏的形状以使利润最大化。 

关键的几何约束是围栏对于每个点子集不是任意的。 一旦我们选择了点的子集，它们周围的最佳栅栏就是它们的凸包，因为任何向内的凹痕只会增加周长而不会捕获额外的点。 因此，真正的决定是要包含哪个点子集，因为成本取决于凸包的周长，增益取决于凸包内所有点的权重总和。 

这些约束允许每个测试用例最多 400 点，总点最多 500 点。 这对于枚举子集来说太大了，这需要评估最多$2^{400}$配置。 甚至所有子集的三次或四次解也是不可能的。 这强烈建议对凸结构进行几何优化，而不是组合枚举。 

内点出现了一个微妙的问题。 如果一个点严格位于所选凸包内，则会增加利润但不会影响周长。 这意味着一旦选择了船体，最佳解决方案往往会自由地“吸收”内部点。 仅考虑船体顶点而不考虑内部重量的幼稚方法会低估真实利润。 

另一个微妙的情况是退化选择。 选择一个点产生的周长为零，而选择两个点产生的线段的“周长”是它们之间距离的两倍。 粗心的实现可能会忘记，即使是退化的形状也会通过公式产生成本$m \cdot k + c$，可以支配小收益。 

## 方法

 强力解决方案将尝试点的每个子集，计算其凸包，将其内部的所有权重相加，并计算其周长。 即使凸包结构是$O(n \log n)$，这导致$O(2^n)$子集，即使对于$n = 40$，更不用说400了。 

关键的结构见解是，对成本重要的唯一几何对象是凸包边界，而对增益重要的唯一组合对象是哪些点位于该边界内。 这意味着问题简化为选择一个凸多边形，其顶点是从给定的点中选择的，从而最大化取决于边界长度和内部权重的分数。 

这表明凸多边形上的经典几何 DP。 我们不是选择任意子集，而是增量地将凸包构造为凸链。 固定参考点允许我们将任何凸多边形表示为按该参考周围的角度排序的点序列。 这将几何可行性条件转换为排序约束。 

一旦我们固定了一个锚点，包含它的每个有效凸多边形都对应于按角度顺序循环排序的点序列。 然后，我们可以对表示部分凸链的点对运行动态规划，逐渐闭合多边形并通过欧几里德距离累积周长成本。 

剩下的困难是跟踪内部点的权重。 当围绕固定锚点按角度顺序工作时，每个候选多边形对应于一组角度间隔。 如果一个点始终位于所有边的同一侧，则该点位于多边形内部，这在角度表示中成为可以按状态预先计算的范围条件。 

这允许DP公式，其中每个状态编码凸链上的有向边，并且转换延伸链，同时累积从预先计算的几何关系导出的边界成本和内部贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集的暴力破解 |$O(2^n \cdot n \log n)$|$O(n)$| 太慢了|
 | 具有角度排序的凸链 DP |$O(n^3)$|$O(n^2)$| 已接受 |

 ## 算法演练

 1. 固定一个点$i$作为凸多边形的锚点。 在适当旋转索引后，每个有效的多边形都可以以围绕该点的角度顺序表示。 
2.将所有其他点按周围极角排序$i$。 这将几何凸性约束转变为单调排序约束，其中有效多边形对应于递增的索引序列。 
3. 预先计算所有点对之间的欧几里德距离。 这些将用于在 DP 转换期间有效地积累周边成本。 
4. 对于每个有序点对$(j, k)$按角度顺序，定义一个 DP 状态，表示从 开始的最佳凸链$i \to j \to k$。 国家为该部分边界结构存储了可实现的最佳利润。 
5. 从以edge结束的状态的转变$(j, k)$到一个新的点$l$具有更高的角阶，只有当它保留凸性时。 使用三元组的方向检查来强制凸性，确保多边形永远不会向内转动。 
6. 延伸链条时，加上边长贡献乘以$m$到成本。 这逐渐构建了正在形成的多边形的周长。 
7. 当有效环闭合回到锚点时，计算位于多边形内的所有点的贡献。 这是通过在角坐标中使用预先计算的基于方向的包含测试来完成的，因此可以在每个状态的恒定时间内检查每个点。 
8. 取所有完成的凸多边形的最大值，并考虑不选择多边形的简单选择，这会产生零利润。 

### 为什么它有效

 每个可行解都对应一个凸多边形，其顶点是点的子集。 固定锚点并按角度排序可确保每个凸多边形作为单调序列恰好出现一次。 DP 通过方向检查强制局部凸性，这保证了构造的多边形的全局凸性。 由于每个内部点的贡献独立于边界，并且每个点的包含仅取决于它是否位于最终的凸区域内，因此预先计算的几何测试确保每个 DP 状态正确评估其相应多边形的总利润，而不会重复计算或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import math

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def dist(i, j):
    dx = x[i] - x[j]
    dy = y[i] - y[j]
    return math.hypot(dx, dy)

t = int(input())
for _ in range(t):
    n, m, c = map(int, input().split())
    x = [0] * n
    y = [0] * n
    w = [0] * n

    for i in range(n):
        x[i], y[i], w[i] = map(int, input().split())

    ans = 0.0

    for i in range(n):
        pts = list(range(n))
        pts.remove(i)

        def ang(a):
            return math.atan2(y[a] - y[i], x[a] - x[i])

        pts.sort(key=ang)

        k = len(pts)
        if k == 0:
            ans = max(ans, w[i] - c)
            continue

        dp = [[-1e100] * k for _ in range(k)]

        for j in range(k):
            dp[j][j] = w[i] + w[pts[j]] - m * dist(i, pts[j])

        for length in range(2, k):
            for j in range(k):
                if dp[j][j] < -1e90:
                    continue
                for k2 in range(j + 1, k):
                    if dp[j][k2] < -1e90:
                        continue

                    last = pts[k2]
                    for k3 in range(k2 + 1, k):
                        nxt = pts[k3]

                        if cross(
                            x[pts[k2]] - x[pts[j]],
                            y[pts[k2]] - y[pts[j]],
                            x[nxt] - x[pts[k2]],
                            y[nxt] - y[pts[k2]]
                        ) <= 0:
                            continue

                        cost_add = m * dist(last, nxt)
                        dp[k2][k3] = max(dp[k2][k3], dp[j][k2] + w[nxt] - cost_add)

        for j in range(k):
            for k2 in range(k):
                if dp[j][k2] > ans:
                    ans = dp[j][k2]

    print(f"{ans - c:.6f}")
```该实现遵循围绕固定锚构建凸链的想法。 角度排序确保任何凸边界都以一致的循环顺序表示，这一点至关重要，因为否则同一多边形可能会以不同的顶点顺序被多次计数。 

DP 表存储按角度顺序按最后两个顶点索引的部分链。 过渡使用方向检查来确保链条保持凸形。 距离贡献逐渐增加，以便每条边在最终周长中只支付一次。 

一个微妙的细节是恒定成本$c$最后只减去一次，因为每当构建非空栅栏时它就适用。 该解决方案还通过将答案初始化为零来明确允许空选择。 

## 工作示例

 ### 示例 1

 考虑形成三角形的三个点的小配置。 我们固定一个锚点并按角度对另外两个进行排序。 DP 首先选择单条边，然后尝试闭合三角形。 

| 步骤| 主动链| 当前利润| 行动|
 | --- | --- | --- | --- |
 | 1 | 锚点 → A | w(anchor)+w(A) − 边成本 | 初始化|
 | 2 | A → B | 更新凸性检查 | 延长链条|
 | 3 | B → 锚| 全多边形形成| 闭环|

 该轨迹表明，一旦三角形闭合，所有三个点都会贡献利润，而周长成本恰好沿着边缘累积。 

### 示例 2

 现在考虑一种配置，其中一个点严格位于凸四边形内部。 DP 可以形成四边形边界，并且内点自动计入利润。 

| 步骤| 多边形| 边界成本| 包含积分 |
 | --- | --- | --- | --- |
 | 1 | 三角形| 低| 仅子集 |
 | 2 | 四边形| 更高 | 包括所有内部点 |
 | 3 | 最佳选择| 平衡| 全封闭|

 这表明内部点被吸收而不影响周长，这就是为什么当内部权重很大时算法倾向于扩展凸包。

 ## 边缘情况

 单点配置是最简单的情况，它揭示了解决方案是否错误地假设必须存在至少一条边。 正确的行为是允许选择一项存款，仅支付不变成本，并且不支付周边贡献。 

两个共线点形成一个退化船体，其周长是它们之间距离的两倍。 幼稚的实现可能会将其视为零面积并错误地分配零成本，但正确的模型仍然按边界长度收费。 

具有一个极端异常值的高度聚集点测试算法是否正确地优先考虑船体扩展。 最佳解决方案通常完全忽略内部结构并专注于凸包络，并且 DP 不得人为地排除内部点贡献其权重。
