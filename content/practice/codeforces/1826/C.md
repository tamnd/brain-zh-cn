 ## 解决方案
 ## 问题理解

 我们有一群`n`反复投票选出最喜欢的程序员`m`算法。 每一轮，每个程序员都会对剩余的选项之一进行投票。 每轮结束后，只有得票数最高的算法才能进入下一轮。 当只剩下一种算法时，该过程结束。 我们被要求确定，对于给定的值`n`和`m`，投票过程是否保证以单一选项终止，或者理论上是否可以永远继续下去（假设程序员进行策略性投票）。 

输入提供`t`测试用例，每个由整数组成`n`和`m`。 如果最终选择了单个选项，则每个测试用例的输出为“是”；如果可能出现无限期的僵局，则每个测试用例的输出为“否”。 

限制因素很大：`n`和`m`都可以大到 10^6，并且`t`最多可达 10^5。 对投票轮次的简单模拟需要生成所有投票分布，这可能高达`m^n`组合。 这在任何实际意义上显然都是不可能的，因此我们每个测试用例都需要一个简单的、恒定时间的逻辑。 

边缘情况出现在以下任一情况下`n`或者`m`非常小。 如果只有一名程序员（`n = 1`），那么无论选项有多少，投票都会以一轮结束。 相反，如果选项数量超过程序员数量（`m > n`），每个算法都有可能获得相同的票数，从而形成平局并防止被淘汰。 例如，与`n = 4`和`m = 2`，如果两个程序员对每个选项进行投票，那么平局将无限期地持续下去，因此正确的输出是“NO”。 

## 方法

 暴力方法将模拟每轮的每种可能的投票模式。 这种方法原则上有效，因为它考虑了程序员可以投票的所有方式，消除了除获得最多票数的选项之外的所有选项。 然而，它在实践中失败了，因为组合的数量呈指数增长。 为了`n = 10^6`和`m = 10^6`，即使模拟一轮在计算上也是不可能的。 

关键的观察是，该过程完全取决于之间的关系`n`和`m`。 如果程序员的数量大于选项的数量（`n > m`），没有办法永远在所有选项中均匀分配选票——至少一个选项最终会获得严格更多的选票，从而减少剩余的选项。 如果选项数量大于或等于程序员数量（`m >= n`），程序员可以平均分配他们的选票，无限期地保持所有选项的平局。 平局可以防止任何淘汰，因此理论上这个过程可以永远持续下去。 

这导致每个测试用例都有一个恒定时间的解决方案：检查是否`n > m`。 如果是，则打印“YES”； 否则，打印“NO”。

 ## 算法演练

 1.读取测试用例的数量，`t`。 每个测试用例都是独立的，因此我们将按顺序处理它们。 
2. 对于每个测试用例，请阅读`n`和`m`。 
3.比较`n`和`m`。 如果`n`严格大于`m`，那么消除最终会将选项减少到一个，因此输出“YES”。 
4. 否则，如果`n <= m`，有可能票数平分，任何一轮都没有选项被淘汰，所以输出“NO”。 
5. 对所有测试用例重复此操作。 

为什么它有效：不变的是程序员和选项之间的关系。 如果程序员的数量多于选项，那么每条平局都可以至少以一种方式打破，从而保证向单个剩余选项前进。 如果选项的数量等于或超过程序员，那么完美的平局总是可能的，并且淘汰可能永远不会发生。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
results = []

for _ in range(t):
    n, m = map(int, input().split())
    if n > m:
        results.append("YES")
    else:
        results.append("NO")

print("\n".join(results))
```该解决方案使用有效地读取输入`sys.stdin.readline`对于大型测试用例。 每次比较`n > m`是在恒定时间内完成的。 结果累积在列表中并立即打印，减少了 I/O 开销。

 ## 边缘情况

 当`n = 1`， 不管`m`，输出为“YES”，如果`m = 1`因为投票就这么简单地结束了。 如果`m > 1`,`n < m`，输出为“NO”，因为程序员无法打破多个选项之间的联系。 

什么时候`m = 1`， 不管`n`，该过程在第一轮结束，所以`n > m`简单地成立并且输出为“YES”。 该算法可以正确处理这两个条件，因为它只检查关系`n > m`。 

该解决方案还可以处理极大的值而不会溢出，因为 Python 整数是无界的并且比较`>`是常数时间。 这确保了最大允许输入的正确性和效率。
