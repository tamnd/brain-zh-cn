 ## 解决方案
 ## 问题理解

 我们有一群人，每个人都声称该组中说谎者的最少数量。 每个人要么总是说真话，要么总是说谎。 我们的任务是确定这些说法是否一致，如果一致，则确定说谎者的可能数量。 如果声明不能一致，我们应该返回-1。 

输入由多个测试用例组成。 对于每个测试用例，我们都会收到人数`n`和一个数组`n`整数`l_i`， 在哪里`l_i`是按人划分的最小说谎者数量`i`。 每个测试用例的输出要么是有效的说谎者数量，要么是 -1（如果声明相互矛盾）。 

限制是适度的：`n`最多可达 100 人，所有测试用例的总人数最多为 10,000 人。 这允许每个测试用例的算法为 O(n log n) 或 O(n²)。 我们不需要考虑高度优化或次线性解决方案。 

非明显的边缘情况包括所有人都声称说谎者为零的情况，每个人都声称说谎者数量最多的情况，或者声明聚集在仅使说谎者计数范围狭窄的值周围的情况。 例如，如果三个人说`[2, 2, 2]`，那么不可能有一个骗子，并且不存在满足所有要求的配置。 粗心的实现可能会在没有检查所有约束的情况下返回一个数字，从而产生错误的答案。 

## 方法

 暴力方法会尝试所有可能的骗子数量，从 0 到`n`并检查索赔是否得到满足。 对于候选说谎者计数`k`，我们将验证至少`k`人们声称至少`k`骗子。 这是有效的，因为说实话的人必须与说谎者的实际数量一致，而说谎者的说法则无关紧要。 验证步骤需要扫描数组，导致每个测试用例的复杂度为 O(n²)。 这是可以接受的`n`最多 100 但效率低下。 

关键的见解是我们不需要任意测试每个数字。 我们可以对声明数组进行排序，并找到声明小于或等于候选说谎者计数的人数与预期计数匹配的最小索引。 更具体地说，如果我们排序`l_i`，然后对于每个可能的说谎者数量`x`, 至少声称的人数`x`骗子至少应该是`x`。 如果这成立，`x`是一个有效的答案。 由于排序，这将问题减少到 O(n log n)，在给定约束的情况下，排序足够快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 可以接受但不是最佳 |
 | 最优（排序+贪婪）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，请阅读`n`以及一系列的权利要求`l`。 
3. 对数组进行排序`l`按非递减顺序。 排序通过将索赔与潜在的说谎者计数对齐来简化检查。 
4. 将结果初始化为-1（假设矛盾）。 
5. 循环可能的骗子计数`x`从 0 到`n`：

 1. 统计有多少人的索赔额大于或等于`x`。 排序后是这样的`n - i`， 在哪里`i`是第一个索引`l[i] >= x`。 
2.如果`x`等于此计数，将结果设置为`x`并打破。 这代表一致的配置：完全一致`x`人们都是骗子，其余的人都说真话。 
6. 打印该测试用例的结果。 

正确性来自于许多说谎者的不变性`x`， 确切地`x`声明必须由说谎者或说真话的人来满足。 排序使我们能够有效地找到对候选人来说可以被视为真实的主张的数量`x`。 仅当候选数等于支持它的声明数时，才存在一致的配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    l = list(map(int, input().split()))
    l.sort()
    result = -1
    for x in range(n + 1):
        # number of people claiming at least x liars
        count = sum(1 for val in l if val >= x)
        if count == x:
            result = x
            break
    print(result)
```该解决方案使用快速 I/O 读取输入，可有效处理多达 10,000 人的数据。 对数组进行排序使我们能够对齐索赔以进行计数。 该循环检查每个可能的骗子计数，计算支持它的声明数量。 返回第一个有效计数，如果不存在则返回 -1。

 ## 边缘情况

 如果所有声明均为零，则算法会正确返回 0 个说谎者。 输入`1 0 0 0`排序为`[0,0,0,1]`; 检查计数`x=0`产生 4，不等于 0； 为了`x=1`索赔数量 ≥1 为 1，匹配`x=1`。 解决方案调整正确。 如果所有索赔均等`n`，算法识别出只有最大计数有效，如输入所示`3 3 3`适合三个人。 无法调和的索赔，例如`[2,2]`，产生-1，因为没有候选者`x`满足等式不变量。 该方法无需任何额外检查即可处理这些边缘情况。
