 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 在每个测试用例中，板上都有一组正整数。 一步操作包括选择这些数字之一并应用确定性变换：如果它是偶数，则它变成自身的一半，如果它是奇数，则它变成该数字的三倍加一。 所选数字将被结果替换，并且该过程继续。 

当每个数字都已减少到无法进一步移动的状态时，测试用例的过程就会停止，这实际上意味着所有数字最终都达到了此转换下的最终值，即 1。 

任务不是实时贪婪地模拟，而是计算在一切稳定之前可以执行的最大移动次数，假设您始终继续执行有效操作，直到无法进行任何操作。 

输入大小限制表明所有测试用例的总数最多为几百个，每个数字最多为一百万。 该语句还保证从值开始直到此限制的任何序列最终都会达到 1，并且在有限的步数内完成。 这立即表明，如果有效完成，每个数字的模拟是可行的，但重复的天真的重新计算轨迹会太慢。 

重复扫描整个阵列并一次应用一个步骤的简单模拟可能会非常昂贵。 如果单个数字需要数百步，有数百个数字，那么总共的运算次数可能达到数万次，如果每次都从头开始重新计算，则会重复重新计算相同的中间状态。 

当幼稚的实现假设独立而不推理重复的子问题时，会出现更微妙的故障模式。 例如，两个不同的数字可能都通过相同的中间值，如 16、8、4、2、1。每次从头开始重新计算链会浪费工作量，并且很容易导致严格限制下的性能问题。 

## 方法

 蛮力的观点是从字面上模拟这个过程。 在每一步中，扫描列表，选择仍然可以操作的任何元素，应用一次转换，然后重复，直到所有值都变为 1。这是正确的，因为它完全遵循过程的定义，但每次移动执行一次扫描。 由于每个数字最多可能需要几百次移动，并且扫描会花费元素数量的线性时间，因此最坏的情况每个测试用例大约为 O(N *total_steps)，当对所有测试用例求和时，这会不必要地缓慢。 

关键的观察结果是，我们应用操作的顺序不会改变每个数字在达到 1 之前变换的总次数。每个数字在确定性规则下独立演化，一旦起始值固定，其轨迹就固定。 全球进程只是将这些独立的轨迹交织在一起。 

这将问题简化为计算每个起始值在给定变换下需要多少步才能达到 1。 一旦我们知道了这一点，测试用例的答案就是该测试用例中所有数字的总和。 

剩下的唯一挑战是有效计算这些高达 10^6 的步数。 直接递归计算会重复重新计算相同的值，因为许多序列严重重叠。 正确的方法是记忆：一旦我们计算出某个值的步数，我们就会存储它并在以后的所有查询中重用它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(总步数 × N) | O(1) 额外 | 太慢了|
 | 记忆化 Collat​​z DP | O(N + 总状态) | O(最大 A) | 已接受 |

## 算法演练

 我们定义一个函数`steps(x)`它返回所需的操作数`x`达到 1。 

1.如果`x == 1`，返回 0。从 1 开始不可能进行进一步的移动，因此这是停止递归的基本情况。 
2. 如果我们已经计算过`steps(x)`，立即返回存储的值。 这可以避免重新计算出现在多个序列中的值。 
3.如果`x`是偶数，计算`steps(x) = 1 + steps(x / 2)`。 原因是，一项操作会立即被减半消耗掉，剩下的过程继续从`x / 2`。 
4.如果`x`是奇数，计算`steps(x) = 1 + steps(3x + 1)`。 同样，第一个操作立即应用，其余操作取决于下一个状态。 
5. 对于每个测试用例，读取所有数字，求和`steps(a_i)`遍历所有元素，并输出结果。 

重要的结构思想是每个数字对总移动计数独立贡献，因此我们不需要模拟不同数字之间的交互。 

## 为什么它有效

 该过程为每个起始值定义了一个确定性链。 一旦选择了一个数字，其未来的演变并不取决于棋盘上的其他数字。 这将全局过程分解为不相交的轨迹。 记忆化确保可达状态空间中的每个整数最多计算一次其步数，因此计算变成隐式状态转换上的有向非循环遍历。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

dp = {1: 0}

def steps(x):
    if x in dp:
        return dp[x]

    if x % 2 == 0:
        dp[x] = 1 + steps(x // 2)
    else:
        dp[x] = 1 + steps(3 * x + 1)

    return dp[x]

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    ans = 0
    for v in arr:
        ans += steps(v)
    print(ans)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```该代码依赖于全局记忆字典`dp`存储已经计算的步数。 递归遵循精确的转换规则。 递归限制会增加，因为链在达到 1 之前可能会变深。 

一个微妙的点是，虽然价值观像`3x+1`可以暂时超出初始约束，该问题保证序列最终恢复并在实践中保持有界。 记忆化确保即使出现较大的中间值，它们也仅被计算一次。 

最后的循环只是聚合独立的贡献，避免对应用操作的顺序进行任何模拟。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(N + U) | 每个可达整数状态计算一次，每个输入数字处理一次 |
 | 空间| O(U) | 备忘录表存储访问值的步数 |

 这里`U`是从输入开始的所有类 Collat​​z 轨迹中遇到的不同值的数量。 考虑到输入最多为 10^6 的约束以及有保证的有界行为，这仍然在一定范围内。 

该解决方案很容易满足时间和内存的限制，因为重复的子问题在朴素递归中占主导地位，而记忆化消除了这种冗余。

 ## 边缘情况

 一种边缘情况是输入包含许多 2 的幂。 在这种情况下，变换纯粹是重复减半，因此序列很短且高度可预测。 该算法可以干净地处理这个问题，因为每个值都会独立减少，并且记忆可以快速重用共享中间体的结果，例如 8 → 4 → 2 → 1。 

另一个边缘情况是当值很小但奇数时，这会迫使 3x+1 分支提前。 例如，从3开始，序列跳转到10，然后合并成与其他数字相同的轨迹。 递归自然地收敛到已经计算的状态，因此存储的结果可以重复使用而无需重新计算。 

最终的边缘情况是在输入数组中重复相同的值。 由于每次出现都独立地查询相同的记忆结果，因此该算法只是重复使用存储的步数并再次添加它，这与棋盘上的每个标记独立演化（即使值一致）的事实相匹配。
