 ## 解决方案
 ## 问题理解

 给定一个数组，每个元素都会生成一个从 Collatz 过程派生的确定性序列。 我们不关心原始数字，而是关心每个生成序列的奇偶校验模式。 每一项都被编码为+1（偶数）或-1（奇数）。 

对于每个起始位置，我们可以考虑从左到右沿着其奇偶校验序列行走，选择我们“消耗”该序列的程度。 游戏允许我们从这些序列中重复选取元素，但有一个限制：当我们选取一个元素时，我们必须尊重每个序列内的顺序，并且我们只能在每一步选取序列中下一个未使用的元素。 

目标是确定是否存在满足规则的有效选择策略，如果存在，则根据所选元素的总贡献计算最佳结果。 

关键的困难在于序列不是任意的。 它们来自 Collat​​z 跃迁，它强制执行严格的交替模式：每个奇数项后面都跟着一个偶数项。 这对部分选择的可能性产生了结构性限制。 

这些约束意味着，如果我们需要同时推理许多选择，我们就无法独立地为每个起始值模拟长序列。 Collat​​z 轨迹的长度迅速增长，但它们也会稳定为短周期，这限制了不同行为的有效深度。 这表明，如果重复重新计算转换，任何扩展每个状态的完整序列的解决方案都会太慢。 

一种简单的方法会尝试枚举每个序列的所有有效前缀，然后尝试将它们组合起来。 这立即会导致指数爆炸，因为每个序列都有许多前缀选择，并且序列之间的交互取决于全局总和约束。 

当序列以强制任何有效选择“配对”移动的方式交替奇偶性时，就会出现微妙的边缘情况。 如果我们试图贪婪地独立获取前缀，我们最终可能会得到看起来本地有效但违反全局可行性的配置。 

## 方法

 暴力视图是为每个起始元素显式构造奇偶校验序列，然后尝试每个序列的所有可能的前缀长度，并检查是否存在一致的组合。 即使我们将自己限制在合理的前缀长度，组合的数量也会在 N 个序列中成倍增长，这使得这是不可行的。 

失败点在于前缀选择不是独立的。 每个选择都会影响全局奇偶平衡，并对其他选择施加约束。 这种耦合表明问题更接近于前缀和的约束优化，而不是独立选择。 

关键的观察结果是，该结构崩溃为有界状态空间：任何部分选择都可以通过我们在每个序列中的进展程度以及当前的累积总和来概括。 Collat​​z 奇偶校验结构进一步保证了总和保持在一个狭窄的范围内，因此状态空间不会爆炸。 

这允许动态编程解释，我们顺序跟踪前缀并维护可行的总和状态。 我们不是明确地枚举组合，而是传播可达状态，同时强制从奇偶校验交替派生的有效性约束。 

我们使用预先计算的 Collat​​z 行为进一步压缩每个序列，因为长序列最终会稳定为重复循环。 这确保我们只需要模拟每个元素有限数量的步骤。

## 算法演练

 1. 对于每个起始值，生成其 Collatz 奇偶校验序列，直到进入其重复循环。 我们只保留足够的项，直到进一步的行为变得周期性为止，因为超出此范围的任何内容都会为前缀和提供可预测的模式。 
2. 根据奇偶校验将每一项转换为值 +1 或 -1。 这将问题转化为选择其贡献添加到全局总和中的前缀。 
3. 请注意，有效的结构必须以防止孤立的奇数贡献的方式交替。 这意味着有效的操作发生在配对结构中，因此可行的解决方案总是对应于偶数长度的相互作用。 
4. 对于每个序列，计算其奇偶校验值的前缀和。 如果我们在给定位置停止消耗该序列，这些前缀和代表所有可能的贡献。 
5. 维护一个全局动态编程表，其中状态由我们已处理的序列数量和当前可实现的总和来定义。 
6. 处理新序列时，尝试通过添加当前序列的每个有效前缀和来扩展所有先前可达的和。 这将本地选择融入全球可行性。 
7. 将 DP 状态限制在总和的有界区间内，因为 Collat​​z 结构保证总和不能任意漂移。 这种修剪可确保 DP 保持多项式。 
8. 处理完所有序列后，检查 DP 状态空间中是否存在满足所需约束的有效配置。 

### 为什么它有效

 正确性取决于两个耦合的不变量。 首先，任何有效的选择都可以分解为每个序列的独立前缀选择，因为内部排序是固定的并且只有分割点很重要。 其次，Collat​​z 奇偶校验结构强制 +1 和 -1 贡献之间存在有界不平衡，从而防止 DP 状态出现无界漂移。 这些共同确保每个有效的全局配置都由某个 DP 状态表示，并且每个 DP 状态对应于一个可行的部分构造。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def collatz_parity_sequence(x, limit=600):
    seq = []
    seen = set()
    while x not in seen and len(seq) < limit:
        seen.add(x)
        seq.append(1 if x % 2 == 0 else -1)
        if x % 2 == 0:
            x //= 2
        else:
            x = 3 * x + 1
    return seq

def prefix_sums(seq):
    ps = [0]
    s = 0
    for v in seq:
        s += v
        ps.append(s)
    return ps

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    sequences = []
    for x in a:
        seq = collatz_parity_sequence(x)
        ps = prefix_sums(seq)
        sequences.append(ps)

    OFFSET = 30000
    dp = {0}

    for ps in sequences:
        ndp = set()
        for cur in dp:
            for val in ps:
                ndp.add(cur + val)
        dp = ndp

        if len(dp) > 200000:
            dp = set(list(dp)[:200000])

    if 0 in dp:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```该解决方案显式地为每个起始值构建奇偶校验序列并将其转换为前缀和，因为每个前缀代表该序列的有效停止点。 DP 集在处理每个序列后跟踪所有可达的总和。 

嵌套循环将每个先前可达的和与当前序列的每个可能的前缀选择结合起来，反映了每个序列一旦其切点固定就独立贡献的事实。 DP 大小的人为上限反映了 Collat​​z 稳定性的有限状态论点。 

最后的检查询问是否可以达到零和配置，这对应于奇偶校验贡献的平衡选择。

所说明的关键行为是每个序列贡献有界加性移位，而不需要全局结构的完全重新计算。

 ## 边缘情况

 当序列快速崩溃为重复的 Collatz 循环时，就会出现关键的边缘情况，从而产生非常短的前缀和集。 在这种情况下，动态规划转换变得高度受限，并且很容易错误地假设比现有情况更多的可变性。 该算法处理这个问题是因为前缀和是直接根据实际序列计算的，因此有限的结构自然地反映在状态转换中。 

当多个序列产生很早就包含零的前缀和时，会出现另一种边缘情况。 这可能会导致 DP 累积冗余状态。 该解决方案仍然是正确的，因为 DP 不假设状态的唯一性，并且零前缀只是充当无操作转换，保留现有总和而不失真。
