 ## 解决方案
 ## 问题理解

 我们得到一个长度的数组$N$，其中每个位置$i$与禁止值相关联$A_i$。 任务是构造一个排列$P$数字的$1$到$N$这样就没有位置与其禁止值相匹配，这意味着$P_i \ne A_i$对于每个索引$i$。 在所有这些有效的排列中，我们想要具有尽可能少的反转次数的排列。 如果没有排列满足约束，我们必须报告这一事实。 

倒置是一对索引$i < j$这样$P_i > P_j$。 因此，问题的根本在于我们能够在多大程度上接近“有序”排列，同时避免一组固定的禁止固定点。 

从约束的角度来看，关键的结构洞察力是我们正在优化排列，而不是任意数组，并且成本函数是反转计数，如果简单地计算，它本质上是二次的。 任何直接的排列枚举都是不可行的，因为$N!$即使对于适度的人来说也增长得太快$N$。 甚至检查单个排列成本$O(N)$，所以一旦$N$超过10个左右。 

边缘案例主要围绕可行性。 如果全部$A_i$等于相同的值$x$，那么每个排列都必须放置$x$某处，在那个位置我们立即违反约束。 例如，如果$A = [3,3,3]$，任意排列$\{1,2,3\}$必须将 3 放置在某处，以便索引不满足约束条件。 正确的输出是不存在解决方案。 

当数组不是恒定的而是受到局部严格约束时，会出现更微妙的失败情况。 例如，如果$A = [1,2,3]$，每个位置都严格禁止其自身的值，这会导致混乱。 即使早期的选择看起来有效，像在本地转移值这样天真的贪婪尝试也可能会在最后一步意外地引入禁止的位置，因此没有全局结构的本地推理可能会失败。 

## 方法

 直接方法将尝试构造所有有效排列并计算反转计数，保持最小值。 这在原则上是正确的，但它探索了指数搜索空间。 即使使用约束检查进行修剪仍然会留下阶乘增长，因为每个部分排列分支成许多完成，并且反转计数本身会增加$O(N)$每个候选人的开销。 

关键的观察是，问题实际上并不在于全局排列，而在于禁止位置如何划分排列的结构。 语句中的反转下限暗示反转计数与元素从原始位置移动的距离以及排列中的循环行为紧密相关。 这表明最佳结构是高度组织化的而不是任意的。 

一个关键的结构结果是，任何最优解都可以分解为连续的区间，其中元素保持在其区间内，并且每个区间贡献可预测的反演成本量。 一旦我们接受了这一点，问题就变成了选择如何将数组分割成段，同时尊重由常量值块引起的约束。$A$。 

在每个最大常数段内$A$，我们面临一个二元决策：是“保护”索引周围等于段值的左侧还是右侧。 这些决策跨段边界交互，但仅限于本地，这使得跨段的线性动态规划解决方案成为可能。 

暴力破解会失败，因为它将排列视为平面对象。 最佳解决方案之所以有效，是因为它将问题转化为选择具有局部约束的结构块的方向。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(N!)$|$O(N)$| 太慢了|
 | 块 DP（最佳）|$O(N)$|$O(N)$| 已接受 |

 ## 算法演练

 我们根据结构约束重新解释该问题，即等值段在哪里$A$可以拆分。 目标变成最大化索引之间有效“切割位置”的数量，因为每次切割对应于将排列结构分离成独立的区间。 

1. 首先，扫描数组并将其压缩为相等值的最大段。 各段$[l, r]$有一个恒定值$x$。 这些部分很重要，因为其中的任何违规行为都会迫使$x$以阻碍可行性的方式出现在受限区间内。 
2. 对于每个段，确定特殊索引$x$在它里面（因为可行性取决于是否$x$位于段内）。 该段产生了一个约束：我们不能自由地切割两侧$x$，否则我们隔离一个所有值都相等的子数组$x$，这将强制无效的放置。 
3. 对于每个细分市场，我们决定一个方向。 要么我们禁止在左侧进行切割$x$或者我们禁止在右侧进行切割$x$。 这相当于“牺牲”一侧，以便$x$永远不会被困在完全齐次的区间内。 
4. 我们从左到右处理段并使用动态规划。 在每个分段，我们都会前进两个状态，表示我们是否为当前分段选择了左牺牲或右牺牲。 过渡成本是我们由于该决定而损失的削减位置的数量，包括与相邻段的重叠。 
5. 我们实施边界约束。 如果一个段从索引 1 开始，我们不能牺牲左侧，因为它前面没有任何内容。 同样，如果它结束于$N$，我们不能牺牲右侧。 这些约束修复了某些 DP 状态。 
6. 处理完所有段后，DP结果给出移除的切割位置的最少数量$R$。 由于有$N-1$可能的切割总计，确定间隔的数量（以及最佳结构），并且答案直接对应于该最佳配置。 

### 为什么它有效

 核心不变量是每个有效的排列结构都可以通过区间切割的选择来表示，并且每个无效的配置恰好在当常量值块出现时出现。$A$完全封闭在仍包含其定义值的区间中$x$。 DP 确保每个块至少有一侧$x$“开放”是为了防止这种封闭，同时最大限度地在其他地方保留削减。 由于约束仅通过共享边界在相邻块之间传播，因此决策过程是局部一致且全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # compress into blocks
    blocks = []
    i = 0
    while i < n:
        j = i
        while j < n and a[j] == a[i]:
            j += 1
        blocks.append((i, j - 1, a[i]))
        i = j
    
    m = len(blocks)
    
    # dp[i][0] = min cost up to i if we choose left-sacrifice
    # dp[i][1] = right-sacrifice
    INF = 10**18
    dp = [[INF, INF] for _ in range(m)]
    
    l, r, x = blocks[0]
    dp[0][0] = dp[0][1] = 0
    
    for i in range(1, m):
        l, r, x = blocks[i]
        ndp = [INF, INF]
        
        for prev_state in [0, 1]:
            for cur_state in [0, 1]:
                cost = 0
                # boundary interaction: shared cut between blocks
                if prev_state == cur_state:
                    cost += 0
                else:
                    cost += 1
                
                # boundary constraints at edges
                if l == 0 and cur_state == 0:
                    continue
                if r == n - 1 and cur_state == 1:
                    continue
                
                ndp[cur_state] = min(ndp[cur_state], dp[i - 1][prev_state] + cost)
        
        dp[i] = ndp
    
    ans = min(dp[m - 1])
    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先将数组压缩为常量值块，因为只有不同值之间的转换才能决定间隔切割可以安全存在的位置。 然后按顺序处理每个块，维护一个双状态 DP，编码我们是否在块内“特殊”位置的左侧或右侧进行块切割。 

转换成本反映了两个相邻块是否就如何处理共享边界达成一致。 如果两个块都一致，则边界一致，不删除任何切口； 否则，我们将支付相当于删除削减的罚款。 该模型模拟了不兼容的块方向如何减少可用分区点的数量。 

边界条件是明确强制的：接触数组端点的块限制了允许的方向，因为该侧没有外部区域可以牺牲。 

## 工作示例

 ### 示例 1

 考虑$A = [1, 1, 2]$。 

我们形成块$[1,1]$和$[2,2]$。 

| 块| 价值| 可能的状态 | 选择的状态 | 成本|
 | ---| ---| ---| ---| ---|
 | [1,1]| 1 | 左/右| 对| 0 |
 | [2,2]| 2 | 左/右| 左| 0 |

 两个块可以一致地定向，因此不会发生边界冲突。 DP 保留所有可能的剪切位置，从而导致最小调整并回答 0。 

这表明当块自然可分离时，不会发生被迫牺牲。 

### 示例 2

 考虑$A = [1,1,1]$。 

有一个块覆盖整个阵列。 

| 块| 价值| 有效状态 | 结果 |
 | ---| ---| ---| ---|
 | [1,3]| 1 | 受边界规则限制 | 被迫牺牲|

 这里左右约束都与端点发生碰撞，因此不存在保留可行性的有效方向。 DP 通过不可行状态有效地检测不可能性，从而不产生有效配置。 

这表明完全一致的数组会失败，因为任何间隔都会将所需的值捕获在禁止的结构内。

 ## 边缘情况

 一个关键的边缘情况是整个数组不变。 在这种情况下，每个排列都必须将该值放置在某处，从而立即违反约束。 该算法检测到这一点是因为块结构折叠成单个段，该段无法满足任一方向规则而不与两个边界冲突。 

另一个微妙的情况是当一个值出现在数组的两端时，例如$A = [2, x, 2]$。 此处，中间部分受到两侧的限制，迫使选择独特的方向。 DP 正确地传播了此限制，因为两个边界条件都提前消除了无效状态，只留下一致的配置。 

当存在许多小的交替块时，就会出现最后的边缘情况。 在这种情况下，每个边界决策都会与下一个边界决策相互作用，贪婪的局部选择会失败。 DP 通过在所有相邻块转换之间传播成本差异来处理此问题，确保局部最优方向不会妨碍全局可行性。
