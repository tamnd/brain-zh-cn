 ## 解决方案
 ## 问题理解

 我们正在处理一个未知的正整数数组，索引从 1 到 N。一个关键的结构承诺是该数组的任何两个不同元素都是互质的，因此它们的最大公约数始终为 1。 

了解有关数组的信息的唯一方法是通过显示两个位置的乘积的查询。 从此类产品中，目标是恢复数组中的每个隐藏值。 

困难在于我们无法直接接触这些元素。 我们必须设计一种使用很少产品查询的策略，其上限严格与 N 成正比，特别是每三个元素最多两个查询。 

约束 N ≤ 100 意味着即使二次方法在技术上也可以通过，但真正的限制是查询预算，而不是计算时间。 任何检查过多对或通过重复查询逐一重建元素的解决方案都会超出允许的交互次数。 

一种简单的方法是查询每对 (i, j)，恢复 gcd 关系，并尝试间接分解值。 这会立即失败，因为它需要 O(N²) 次查询，即使 N = 100，这也远远超出了允许的限制。 

更微妙的失败案例来自尝试仅使用相邻产品独立恢复每个元素。 例如，如果我们只计算 a1·a2、a2·a3、a3·a4 并尝试在没有结构化分组的情况下隔离值，我们最终会丢失边界值或每个元素需要额外的查询，从而超出查询预算。 

核心挑战不是代数重建本身，而是以跨元素摊销信息的方式进行。 

## 方法

 暴力策略会将每个未知值视为独立的，并尝试使用多个产品查询来隔离它。 例如，人们可能会尝试通过查询 (i, j) 中的许多 j 值并间接使用 gcd 关系来计算 a[i]。 虽然正确性不难争论，但这种方法会退化为 O(N²) 查询，因为每个值都需要针对许多其他值进行重复确认。 

关键的结构观察是单个产品查询已经对两个未知值进行乘法编码，并且互质条件防止了因子重叠中的歧义。 这意味着如果我们采用共享一个中间元素的两个产品，则可以使用 gcd 操作干净地提取该中间元素。 

具体来说，假设我们查询产品 x = a[i]·a[j] 和 y = a[j]·a[k]。 它们的 gcd 是 a[j]，因为 a[i] 和 a[k] 除了自身之外不与任何事物共享质因数，因此所有共享结构都必须来自 a[j]。 一旦a[j]已知，a[i]和a[k]都可以通过直接除法得到。 

这创建了一个自然的 3 元素重建块：两个查询准确地确定所有三个值。 一旦认识到这一点，整个数组就可以分为不相交的三元组，每个三元组独立求解。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N² 查询) | O(1) | O(1) | 太慢了|
 | 三重封锁| O(N 查询) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 将索引范围拆分为三个元素的连续组。 对于组 (i, i+1, i+2)，我们将使用两个产品查询来恢复所有三个值。 这种分组确保每个查询提供最大的信息。 
2. 查询组中前两个元素的乘积，得到x = a[i]·a[i+1]。 然后查询最后两个元素的乘积，得到y = a[i+1]·a[i+2]。 
3. 将中间元素 a[i+1] 计算为 gcd(x, y)。 这是可行的，因为两个乘积都包含 a[i+1]，而 a[i] 和 a[i+2] 与除自身之外的所有内容互质，因此它们对 gcd 没有贡献。 
4. 一旦知道a[i+1]，通过直接除法恢复剩余的两个元素：a[i] = x / a[i+1] 和a[i+2] = y / a[i+1]。 此步骤是有效的，因为乘积是精确的，并且由于互质属性不存在歧义。 
5. 对每个完整的三元组重复此过程。 如果 N 不能被 3 整除，则使用相同的乘积查询和除法逻辑，将剩余的一或两个元素与先前三元组中已知的恢复值配对来处理。 

### 为什么它有效

 不变量是每个数字仅参与其素因数唯一出现的乘积。 因为所有不同的元素都是成对互质的，所以两个乘积的任何 gcd 都精确地隔离了三元组中共享的中间元素。 一旦该元素被恢复，每个查询的乘法结构就变得完全可逆。 任何步骤都不会引入歧义，因为没有两个不同的值可以共享会干扰因子恢复的素因子。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# NOTE: This is written as if an interactive judge provides a query function.
# In a real interactive problem, replace `query(i, j)` with stdout flush and read.

def query(i, j):
    print("?", i, j, flush=True)
    return int(input())

def answer(arr):
    print("!", *arr, flush=True)

def solve():
    n = int(input())
    a = [0] * (n + 1)

    i = 1
    while i + 2 <= n:
        x = query(i, i + 1)
        y = query(i + 1, i + 2)

        # middle element
        mid = gcd(x, y)
        a[i + 1] = mid

        a[i] = x // mid
        a[i + 2] = y // mid

        i += 3

    # handle leftover
    if n % 3 == 1:
        # single element, must be deduced from any known pair
        # assume n > 1 and a[n-1] known
        a[n] = query(n-1, n) // a[n-1]

    elif n % 3 == 2:
        # last two elements, use known neighbor from previous block
        a[n-1] = query(n-2, n-1) // a[n-2]
        a[n] = query(n-1, n) // a[n-1]

    answer(a[1:])

if __name__ == "__main__":
    from math import gcd
    solve()
```实现直接遵循三重分解。 每个块恰好发出两个查询，并且 gcd 步骤隔离共享的中间元素。 一旦知道这一点，整数除法就会毫无歧义地重建外部元素。 

一个微妙的实现细节是 gcd 必须在任何除法之前应用。 颠倒这个顺序就会失去系统中唯一坚固的锚点。 另一个重要的一点是，所有索引在概念上都是基于 1 的，这与交互公式相匹配，并避免在对三元组进行分组时出现差一混淆。 

剩余处理假设至少一个邻居已从前一块重建，这是有效的，因为分组根据 N 模 3 确保重叠或邻接。 

## 工作示例

 考虑 N = 6 和数组 [2, 3, 5, 7, 11, 13]。

 | 2 | (2,3) | 15 | 15
 | 3 | 最大CD(6,15) | 3 |

 对于第二个三元组：

 | 步骤| 查询 | 结果 |

 该迹线表明每个三元组是完全独立的，并且不需要三元组之间的交互。 gcd 步骤始终隔离共享中心元素。

 ## 边缘情况

 对于 N = 3，该算法恰好执行两次查询并重建单个块中的所有值。 gcd 步骤直接识别中间元素，除法产生两个端点，而不需要任何额外的结构。 

对于 N = 4，第一个三元组重建索引 1 到 3。然后使用索引 3 的单个乘积查询恢复索引 4 处的剩余元素，索引 3 已从前一个块中获知，从而允许除法安全地恢复 a4。 

对于 N = 5，第一个块重建 1 到 3，并且根据排序使用两个依赖查询通过索引 3 或 4 处理剩余的对 (4,5)。 由于在最终恢复之前至少有一个邻居是已知的，因此划分仍然是明确定义的且明确的。
