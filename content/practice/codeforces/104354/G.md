 ## 解决方案
 ## 问题理解

 我们被要求将数学表达式转换为以下形式$x^y$成固定大小的 ASCII 图稿。 每个测试用例给出两个正整数的字符串表示$x$和$y$，我们必须根据 的值决定绘制什么$z = x^y$。 

如果$z \le 10^{18}$，我们画出完整的表达式$x^y = z$。 否则，我们用字符串替换整个结果端`INF`，生产$x^y = INF$。 

该绘图不是通常意义上的文本，而是由连接预定义字形确定的高度为 10 且宽度确定的像素网格。 每个数字和符号都绘制为 7×7 的块，但指数数字除外，指数数字绘制为 5×5 的块并且位置稍高。 每个字符在水平方向上都由一列点分隔开，并且画布两侧都有一列填充。 

核心计算部分不是渲染本身，而是决定是否$x^y$超过$10^{18}$如果不是，则以安全的方式计算其确切值。 限制条件$x, y \le 10^{18}$立即意味着直接求幂一般来说是不可能的，因为即使$2^{60}$已经超过$10^{18}$，并且许多输入在完全计算之前很久就会溢出。 

一种简单的计算方法$x^y$直接会溢出时间和整数限制。 即使Python的大整数在像10^{18}^{10^{18}}这样的情况下也会变得太大，这在天文数字上是不可行的。 因此，真正的任务简化为尽早确定溢出，并且仅在安全范围内计算精确值。 

出现微妙的边缘情况时$y = 1$。 在这种情况下，该值恰好是$x$，并且即使在$x$很大但仍在范围内。 另一个边缘情况是$x = 1$，其中结果始终为 1，无论$y$，因此求幂逻辑应立即短路。 

## 方法

 暴力解决方案从字面上解释问题：计算$x^y$完全，将其与$10^{18}$，然后决定是打印还是打印`INF`。 这原则上是正确的，因为 Python 或大整数算术可以表示任意大的值。 

然而，当这种方法变得不可行时$y$很大。 重复乘法需要$O(y)$运算，甚至快速求幂仍然会产生大小爆炸的中间值。 真正的瓶颈不仅是时间，还有内存和算术增长：值很快就会超出任何实际界限。 

关键的观察是我们实际上并不需要的全部价值$x^y$。 我们只需要知道它是否超过$10^{18}$，如果不存在，我们可以安全地计算它。 这使我们能够将所有中间结果限制在$10^{18} + 1$。 一旦运行的产品超过阈值，我们可以提前停止并返回`INF`立即地。 

这将求幂转换为快速功率的有界模拟，其中我们故意丢弃超出阈值的精度。 二进制求幂的结构仍然适用，但具有饱和运算。

 | ---| ---| ---| ---|
 | 蛮力 |$O(y)$或者更糟|$O(1)$到大| 太慢了 |
 | 有界二进制幂 |$O(\log y)$|$O(1)$| 已接受 |

 ## 算法演练

 我们计算$x^y$使用二进制求幂，但上限截止为$10^{18} + 1$。 

1.如果$x = 1$或者$y = 0$，我们立即返回 1，因为结果始终在范围内。 这避免了不必要的计算。 
2. 将结果初始化为1，并设置一个限值为$10^{18}$。 
3.同时$y > 0$，检查最低位$y$。 如果设置了，则将当前结果乘以$x$，但如果乘法超出限制，我们将限制它并将结果标记为溢出。 
4. 正方形$x$在每一步中，如有必要，再次将其限制在限制范围内。 这确保了中间力量永远不会超出我们关心的范围。 
5. 转变$y$向右移动一点并继续。 
6. 循环结束后，如果触发了溢出，我们输出`INF`。 否则，我们输出计算值。 

我们限制价值而不是让它们自然增长的原因是任何超过的价值$10^{18}$对于输出目的是无法区分的。 我们只需要区分“有效”和“溢出”。 

### 为什么它有效

 二进制求幂将指数分解为 2 的幂，通过独立贡献的乘法确保正确性。 由于乘法在正整数上是单调的，一旦部分积超过$10^{18}$，它永远不会通过进一步的乘法返回到阈值以下。 这种单调性允许安全地提前停止，而不影响溢出决策的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

LIMIT = 10**18

def power(x, y):
    result = 1
    overflow = False

    while y > 0:
        if y & 1:
            result *= x
            if result > LIMIT:
                overflow = True
                result = LIMIT + 1
        y //= 2
        if y:
            x *= x
            if x > LIMIT:
                x = LIMIT + 1

    return result, overflow

def solve_case(s):
    base, exp = s.split('^')
    x = int(base)
    y = int(exp)

    if x == 1:
        return "1"
    if y == 1:
        return str(x)

    val, overflow = power(x, y)
    if overflow or val > LIMIT:
        return "INF"
    return str(val)

def main():
    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        out.append(solve_case(s))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```解析步骤直接根据插入符号格式将表达式拆分为基数和指数。 特殊情况检查$x = 1$和$y = 1$防止不必要的求幂，并避免边缘情况下意外的溢出逻辑错误。 

幂函数是一个标准的二进制求幂循环，但每个乘法后面都有一个钳位$10^{18} + 1$。 这确保了 Python 整数的增长永远不会超出我们决策所关心的范围。 

溢出标志是必要的，因为单独钳位会丢失有关真实值是否超出限制的信息。 没有标志，值就像$10^{18} + 5$与一个永远不会很大但在中间步骤中受到限制的值没有区别。

 ## 边缘情况

 对于输入，其中$x = 1$，算法立即返回 1，而不输入求幂。 这是正确的，因为 1 的任何幂都保持为 1，并且它避免了不必要的乘法链，否则会浪费时间。 

对于输入，其中$y = 1$，算法返回$x$直接地。 这可以避免触发二进制求幂逻辑，否则即使不需要求幂，二进制求幂逻辑也会重复进行平方和乘法。 

对于非常大的$x$和$y$，例如 10^{18}^{10^{18}}，上限乘法确保值永远不会增长超过$10^{18} + 1$。 溢出标志在第一次超过阈值的乘法时变为真，并且算法正确输出`INF`却从未构建出真正的价值。
