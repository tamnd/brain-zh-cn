 ## 解决方案
 ## 问题理解

 我们得到一个长度为一百万的二进制字符串，它是由两个基于固定种子的伪随机位生成器之一生成的。 

第一个生成器是标准 XorShift64 机器。 它从种子开始一次，然后永远演变为 64 位状态。 每个输出位都取自演化状态。 由于状态永远不会重置，因此生成的序列是单个连续的确定性流。 

第二个生成器是有缺陷的版本。 它仍然使用相同的 XorShift64 转换规则，但它反复将状态重置回初始种子。 然后它生成固定数量的位，再次重置，生成另一个块，然后继续。 这些块的长度未知，但它们的总和正好是一百万，并且每个块的长度至少为十。 关键的效果是每个块都从完全相同的初始状态重新启动，因此每个块都以底层 XorShift 序列的相同前缀开始。 

任务是确定给定的字符串是否可以来自正确的不间断生成器，或者是否必须来自基于重置的有缺陷的生成器。 

规模上的限制极其严格，字符串长度可达一百万。 任何试图直接模拟或测试所有可能的分段的解决方案都是不可能的，因为原则上可能的分区的数量呈指数增长。 这立即排除了任何试图通过暴力猜测块边界的方法。 

当字符串几乎一致或高度重复时，就会出现微妙的边缘情况。 在这种情况下，在有缺陷的生成器下，许多不同的分割似乎是合理的，而天真的贪婪分割可能会错误地接受无效的构造。 另一种故障模式是假设块边界是本地可检测的，因为边界的有效性取决于与全局种子派生前缀的一致性，而不仅仅是本地模式。 

## 方法

 两个生成器之间的主要区别在于状态的连续性。 正确的生成器生成单个流，而有缺陷的生成器生成相同底层序列的多个独立前缀，每个前缀都从相同的种子重新启动。 

这意味着在有缺陷的生成器下，每个块都是从种子生成的相同无限确定性序列 A 的前缀。 所以整个字符串是由段连接而成的，每个段的形式都是 A[0 : len]。 

暴力方法会尝试在每个可能的边界集处分割字符串，并验证每个片段是否与生成序列的前缀匹配。 这是不可行的，因为分区数量呈指数级增长，甚至检查单个分区也涉及对潜在多个段的线性工作。 

关键的观察是，整个问题简化为检查我们是否可以将字符串划分为段，使得每个段都与同一参考字符串 A 的前缀匹配，并且每个段的长度至少为 10。 如果我们假设 A 等于从种子开始的真实生成的前缀，则每个有效段都必须匹配 s[0 : len]。 这将问题变成了检查我们是否可以用前缀匹配块贪婪地覆盖字符串。 

在每个位置 i，唯一有意义的量是 s[i:] 和 s[0:] 之间的最长前缀匹配。 如果我们知道这个值，我们就可以决定在有缺陷的生成器假设下，一个段可以从 i 开始延伸多远。 该结构变得贪婪，因为尽可能扩展段永远不会降低后面位置的可行性。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力分割| 指数| O(1) | O(1) | 太慢了 |
 | 前缀匹配+贪心分割| O(n) | O(n) | 已接受 |

 ## 算法演练

 核心思想是预先计算字符串的每个后缀与前缀的匹配程度，然后贪婪地切割有效段。 

1. 计算数组 Z，其中 Z[i] 是最长长度，使得 s[i : i + Z[i]] 等于 s[0 : Z[i]]。 这捕获了从 i 开始的片段可以模仿种子序列所需前缀的长度。 
2. 从位置 0 开始扫描字符串。设当前位置为 i。 
3. 如果i等于字符串长度，则切分成功。 
4. 对于每个位置 i，我们需要一个从这里开始的有效段。 该段的长度必须至少为 10，因此如果 Z[i] 小于 10，我们就无法在有缺陷的生成器假设下形成有效的块。 
5. 选择段长度为 Z[i]。 这是从 i 开始仍与所需前缀结构匹配的最大可能有效块。 
6. 将 i 向前移动 Z[i] 并重复。 
7. 如果在任何时候我们无法前进（Z[i] < 10），有缺陷的生成器解释就会失败。 

它的工作原理与越野车发电机的结构有关。 每个段必须等于相同基础序列的前缀，因此从 i 开始的唯一可能的有效段完全取决于字符串与该前缀匹配的长度。 任何较短的切割都是不必要的，因为扩展段不会破坏一致性，并且根据 Z[i] 的定义，任何更长的扩展都是不可能的。 这使得贪婪选择变得安全：一旦一个段开始，它的最大有效范围是固定的，并且未来的决定不依赖于在该点选择更小或更大的有效前缀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

# Z-function computation
z = [0] * n
l = r = 0
for i in range(1, n):
    if i <= r:
        z[i] = min(r - i + 1, z[i - l])
    while i + z[i] < n and s[z[i]] == s[i + z[i]]:
        z[i] += 1
    if i + z[i] - 1 > r:
        l, r = i, i + z[i] - 1

i = 0
while i < n:
    if i == 0:
        seg_len = n
    else:
        seg_len = z[i]
    if seg_len < 10:
        print("No")
        break
    i += seg_len
else:
    print("Yes")
```该解决方案依靠 Z 阵列来有效测量前缀一致性。 第一个段总是可以选择覆盖整个字符串，因为它与自身进行比较，因此我们将其长度设置为 n。 对于后面的位置，Z 值准确地告诉我们在保持与种子前缀行为相等的同时可以将段延伸多远。 

一个常见的实现陷阱是忘记每个段的长度必须至少为 10 的约束。 这是 Z 计算之外唯一需要的硬可行性检查。 另一个微妙的点是我们从不在一个位置尝试替代分割。 一旦 Z[i] 已知，该结构就会在越野车模型下强制该段具有唯一的最大连续性。

### 示例 2

这表明该算法不会任意切割字符串，仅在前缀一致性强制重新启动时才进行分割。

    import sys

    n = len(s)

    l = r = 0

 ## 边缘情况

 一种边缘情况是字符串高度均匀，例如全零。 在这种情况下，每个后缀都与前缀完全匹配，因此 Z[i] 对于所有 i 来说都会变大。 该算法会将整个字符串视为一个片段，这是有效的并且正确匹配正确的生成器场景。 

当第一个不匹配较早发生时，就会出现另一种边缘情况。 假设字符串以长统一前缀开头，然后发散。 在发散位置 i，Z[i] 变小，可能低于 10。 该算法立即拒绝有缺陷的生成器模型，因为没有有效的段可以从那里开始，这符合每个块的长度必须至少为 10 的要求。 

第三种边缘情况是当字符串被结构化时原则上可以存在多个分段。 即使如此，Z 阵列也会在每个位置强制执行唯一的最大延伸，因此该算法不依赖于猜测边界。 这完全避免了歧义，并确保即使许多分区看起来合理时也能保持一致的行为。
