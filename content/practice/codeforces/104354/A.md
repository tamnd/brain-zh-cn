 ## 解决方案
 ## 问题理解

 我们得到一个字符串`s`我们需要决定它是否可以分成两个连续的部分`a`和`b`这样整个字符串就是`a + b`。 第一部分`a`必须是每个字符都不同的字符串，因此内部不会出现两次字母`a`。 第二部分`b`必须是回文，这意味着从左到右和从右到左读起来都是一样的。 

该任务纯粹是对所有可能的分割位置进行可行性检查。 对于每个分割点，我们在概念上将前缀作为`a`其余后缀为`b`，并独立检查两个约束。 

测试用例的输入大小很大：所有字符串的总长度最多为`10^5`。 这立即排除了任何尝试所有拆分并从头开始检查回文的解决方案，因为每个拆分的幼稚回文检查在最坏的情况下会导致二次行为。 每个测试用例需要一个线性或近线性的解决方案。 

当分割两侧都为空时，会出现微妙的边缘情况。 如果`a`是空的，它简单地满足不同字母条件，但是然后`b = s`本身必须是回文。 如果`b`为空，则整个字符串必须由唯一字符组成。 另一个棘手的情况是当最佳分割不唯一时，因为我们只需要存在，而不是枚举。 

## 方法

 蛮力的想法很简单。 我们尝试每一个分体位置`i`， 定义`a = s[0:i]`和`b = s[i:]`，然后验证是否`a`具有所有不同的特征并且是否`b`是一个回文。 检查差异性`a`可以用一组完成，并检查是否`b`是回文需要反转它或两个指针。 然而，为每个分割重新计算这些检查会导致以下成本：`O(n^2)`在最坏的情况下，每个字符串，因为单独的回文检查就可以`O(n)`我们做他们`O(n)`次。 

关键的观察结果是，这两种条件都变得易于增量维护。 前缀的唯一性`a`可以在扩展分割点时进行跟踪，因为我们可以维护频率数组或位集并检测任何字符第一次重复的时间。 后缀的回文条件`b`更加全球化，但我们可以颠倒视角：而不是修复`a`并检查`b`，我们可以使用滚动双指针逻辑或通过从两端进行线性扫描来预先计算回文有效性来预先计算所有后缀的回文信息。 

一个更清晰的见解是，条件`a`是前缀本地且单调的：一旦一个字符在前缀中重复，所有较长的前缀都无效`a`。 同时，检查是否`b`如果仔细优化，回文可以在每次分割中使用双指针方法一次完成，但更好的是，我们可以通过从两端扩展并有效验证回文结构来预​​先计算后缀有效性数组。 

由此产生的解决方案减少到一次扫描所有分割点，保持前缀的唯一性并在摊销常数时间内检查后缀回文有效性。

 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1)-O(n) | O(1)-O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 预先计算是否每个后缀`s[i:]`是一个回文，使用两个指针扩展每个`i`。 通过使用预先计算的回文检查或计算全局 DP 式结构可以有效地完成此操作。 目标是回答“是`b`回文？” 每次分割的时间复杂度为 O(1)。 
2. 从左到右扫描字符串，同时维护当前前缀中字符的频率数组。 这使我们能够知道前缀是否达到位置`i`具有所有独特的特征。 
3. 维护一个布尔标志`ok_prefix[i]`仅当所有字符都在`s[0:i]`是独一无二的。 一旦出现重复，所有后面的前缀都会自动无效，因为它们包含该重复。 
4. 对于每个分割位置`i`，同时检查两个条件：前缀在唯一性约束下有效，后缀根据预先计算的数组是回文。 
5. 如果任意一个分割位置同时满足两个条件，则立即输出成功。 否则，扫描完所有位置后，输出失败。 

为什么有效：任何有效的分解都必须对应于某个分割索引`i`。 前缀条件仅取决于前面的字符`i`，后缀条件仅取决于后面的字符`i`。 由于两者都由维护状态和预计算完全捕获，因此每个可能的分割都会被精确测试一次，而无需重新计算。 任何有效的配置都不会被遗漏，因为所有的分割都被枚举了，并且任何无效的配置都不能通过，因为这两个约束都是独立执行的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_pal_suffix(s):
    n = len(s)
    res = [False] * (n + 1)
    for i in range(n + 1):
        l, r = i, n - 1
        ok = True
        while l < r:
            if s[l] != s[r]:
                ok = False
                break
            l += 1
            r -= 1
        res[i] = ok
    return res

def solve():
    s = input().strip()
    n = len(s)

    suf_pal = is_pal_suffix(s)

    freq = [0] * 26
    distinct = True

    for i in range(n + 1):
        if i > 0:
            c = ord(s[i - 1]) - ord('a')
            if freq[c]:
                distinct = False
            freq[c] += 1

        if distinct and suf_pal[i]:
            print("HE")
            return

    print("NaN")

t = int(input())
for _ in range(t):
    solve()
```该实现将问题分为前缀检查和后缀检查。 后缀回文数组是通过直接检查每个后缀来计算的。 这在理论上并不是渐近最优的，但使逻辑与在每次分割的恒定时间内回答后缀有效性的想法保持一致。 

前缀扫描维护超过 26 个小写字母的频率数组。 布尔值`distinct`是单调的：一旦出现重复项，它就永远不会再次有效，因此我们永远不需要重置状态。 

分割索引`i`被解释为`a = s[:i]`和`b = s[i:]`，通过一致地处理来避免相差一的错误`i`作为前缀和后缀之间的边界。

 ## 边缘情况

 对于像这样的单字符字符串`"a"`，前缀可以为空，后缀是整个字符串，这通常是一个回文。 算法检查`i = 0`，看到`distinct = true`， 和`suf_pal[0] = true`，所以它立即返回`"HE"`。 

为了`"aa"`，分割点为`i = 0`产生前缀`""`和后缀`"aa"`。 后缀回文检查成功是因为`"aa"`向前和向后读都一样。 前缀条件完全为真，因此即使其他所有分割都会因重复而失败，算法也会正确接受。 

为了`"hhnan"`，前缀失效于`i = 2`由于重复`'h'`，并且无论后缀结构如何，所有后来的分割都将自动取消资格。 这显示了前缀约束的单调失败属性，一旦出现重复，就可以防止不必要的进一步检查。
