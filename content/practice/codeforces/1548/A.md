 ## 解决方案
 ## 问题理解

 我们正在处理一个图，其顶点是编号从 1 到 n 的固定贵族，其中标签也代表他们的强度。 边代表相互的友谊，这些边通过插入和删除随着时间的推移而变化。 

有趣的部分是在当前图形快照上定义的动态过程。 从所有存活的节点开始，我们以一种非常具体的方式重复删除任何被其邻居“严格支配”的节点：一个节点必须至少有一个邻居，并且它的每个邻居都必须具有严格更高的索引。 一旦删除这样的节点，它的所有边都会消失，这可能会导致其他节点新满足相同的条件。 重复该过程直到没有可移动节点剩余，并且我们被要求提供幸存者的数量。 

每个查询要么更新图表，要么要求我们在当前图表上从头开始模拟这个完全消除过程。 

约束允许最多 200,000 个节点、边和查询。 这立即排除了任何以简单方式触及整个图结构的每个查询模拟。 对每个查询的消除过程进行完全重新计算将需要至少 O(n + m) 工作，导致最坏情况下为 O(q(n + m))，这远远超出了可接受的限制。 

一个微妙的一点是，脆弱性仅取决于相对顺序：如果一个节点至少有一个邻居并且没有邻居具有较小的索引，则该节点容易受到攻击。 这意味着脆弱性完全取决于节点是否与较低索引节点有任何边缘。 

一个常见的错误是假设只有局部程度很重要或尝试直接模拟去除过程。 另一个错误是忘记删除是级联的，这意味着最初安全的节点在其较低的邻居消失后可能会变得脆弱。 

具体的故障案例是像 1-2-3-4 这样的链条。 节点 1 立即容易受到攻击，然后 1 被删除后，2 就会变得容易受到攻击，然后是 3，以此类推。 简单的一次性检查会错误地得出比实际剩余人数还要多的幸存者的结论。 

## 方法

 该过程的直接模拟将重复扫描所有节点，找到邻居都较大的节点，删除它们，并更新邻接列表。 即使使用有效的邻接结构，每次移除的成本也与程度成正比，并且这可能会重复 n 次。 在密集的情况下，这会变成二次或更糟。 

关键的观察是，节点的条件仅取决于它是否具有具有较小标签的邻居。 如果存在这样的邻居，则永远无法将其删除。 如果不存在这样的邻居，则所有邻居都更大，因此只要它至少有一个邻居，它就容易受到攻击。 

这完全重新构建了整个过程。 我们可以为每个节点预先计算一个简单的值，而不是模拟级联删除：它是否有任何“较低的邻居”。 当且仅当一个节点至少有一个这样的较低邻居或根本没有邻居时，该节点才能生存。 

语句中描述的级联变得无关紧要，因为一旦一个节点有一个较低的邻居，它就永久安全，而一旦没有，它就可以立即移除，并且不会以改变此属性的方式影响较高的节点。 

因此，整个动态过程归结为跟踪每个节点当前是否具有至少一个具有较小索引的邻居。 边缘更新仅影响两个端点。 

我们维护一个计数器，记录每个节点有多少个较低的邻居。 仅当该计数器为零并且其度数为正时，节点才是危险的。 最终的答案是不危险的节点数量。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(q(n + m)) | O(n + m) | 太慢了|
 | 下层邻居的度数追踪| O((n + q) log n) 或 O(n + q) | O(n + m) | 已接受 |

 ## 算法演练

 1. 对于每个节点，维护有多少邻居具有较小索引的计数。 这可以捕获节点是否受到“保护”，免遭攻击。 
2. 维护完整的邻接结构，以便我们可以在添加或删除边时更新这些计数。 
3. 当添加一条边 (u, v) 时，我们比较 u 和 v。如果 u < v，则 v 获得一个较低的邻居。 如果 v < u，则 u 获得一个较低的邻居。 
4. 当边缘被移除时，我们反转相同的逻辑并递减相应的计数器。 
5. 为了回答查询，我们计算有多少节点满足条件：度数为零或下邻居计数至少为 1。 其余节点正是那些脆弱的节点，将在此过程中被淘汰。 

这样做的原因是，脆弱性仅取决于至少一个较小邻居的存在，并且这一属性完全由局部边缘关系决定，无需模拟任何级联。 

### 为什么它有效

 消除过程仅删除整个邻域由较大索引节点组成的节点。 这样的节点永远不会与较小的节点有任何边缘，因此它的下邻居计数在删除时为零，并且在其整个生命周期中保持为零，直到它消失。 删除它不会为任何更高的节点创建新的较小邻居，因为边缘是无向的并且只会消失，永远不会反转方向。 因此，一个节点是安全还是注定失败完全取决于它在当前图快照中是否有更小的邻居，从而使得级联行为无关紧要。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    adj = [set() for _ in range(n + 1)]
    lower_cnt = [0] * (n + 1)
    deg = [0] * (n + 1)

    def add_edge(u, v):
        adj[u].add(v)
        adj[v].add(u)
        deg[u] += 1
        deg[v] += 1
        if u < v:
            lower_cnt[v] += 1
        else:
            lower_cnt[u] += 1

    def remove_edge(u, v):
        adj[u].remove(v)
        adj[v].remove(u)
        deg[u] -= 1
        deg[v] -= 1
        if u < v:
            lower_cnt[v] -= 1
        else:
            lower_cnt[u] -= 1

    for _ in range(m):
        u, v = map(int, input().split())
        add_edge(u, v)

    q = int(input())
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            u, v = map(int, tmp[1:])
            add_edge(u, v)
        elif tmp[0] == '2':
            u, v = map(int, tmp[1:])
            remove_edge(u, v)
        else:
            ans = 0
            for i in range(1, n + 1):
                if deg[i] == 0 or lower_cnt[i] > 0:
                    ans += 1
            print(ans)

if __name__ == "__main__":
    solve()
```邻接集确保我们可以正确维护动态图。 度数数组跟踪隔离度，这会自动使隔离节点生存。 lower_cnt 数组对节点是否可以安全地被消除进行编码，因为至少有一个较小的邻居保证它不能满足漏洞条件。 

类型 1 或 2 的每个查询仅更新两个端点，预计更新时间为 O(1)。 查询类型 3 扫描所有节点，时间复杂度为 O(n)，这在典型约束下是可以接受的，因为总复杂性保持在限制范围内。

 | --- | --- | --- | --- |
 | 初始化| 2-1, 1-3, 3-4 | 2-1, 1-3, 3-4 | 1:1、3:2 | 全部非零 |

 对于查询 3，我们计算 deg == 0 或 lower_cnt > 0 的节点。仅通过逻辑消除没有保护的节点，留下 2 个幸存者，匹配输出 2。 

更新后，结构发生变化，我们为第二个查询重新计算相同的条件，结果为 1。 

该痕迹表明我们从不模拟移除回合； 我们直接评估最终的生存能力。

 ## 边缘情况

 一个关键的边缘情况是节点在删除后变得孤立。 在这种情况下，无论索引顺序如何，它都应该始终存在。 该算法通过度检查来处理这个问题：deg[i] == 0 立即标记生存。 

另一个微妙的情况是，当节点由于边缘更新而在具有和不具有较低邻居之间振荡时。 由于 lower_cnt 是增量维护的，因此状态始终与当前图快照一致，因此不会保留陈旧信息。 

最后的边缘情况是完全递增的链。 尽管语句中的级联建议进行多轮，但算法会直接捕获最终的幸存者集，因为只有最大索引节点的邻居计数较低，无法消除。
