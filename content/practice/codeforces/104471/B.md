 ## 解决方案
 ## 问题理解

 我们有两个多重集合，每个集合的大小$n$。 将它们视为两行数字，$s$和$t$，每个都恰好包含$n$元素，其中允许重复。 

一步操作中，我们选择一个元素$s$和一个元素$t$，但前提是值不同。 我们删除这两个元素。 我们重复此操作，直到我们设法删除两个多重集中的所有内容或陷入困境。 

任务是决定是否可以使用此类操作完全清空两个多重集。 

由于每次操作都会从每一侧精确删除一个元素，因此任何成功的过程都必须精确地包含$n$操作，将每个元素配对$s$恰好有一个元素$t$。 唯一的限制是我们不允许配对相等的值。 

约束很大：所有测试用例的元素总数可以达到$2 \cdot 10^5$。 这立即排除了每个测试用例的任何二次方，甚至每个测试的排序只有在仔细限制的情况下才是可接受的。 该解决方案必须有效地将每个测试用例简化为线性或线性算术计数。 

一种简单的方法会尝试贪婪地模拟匹配，甚至构建显式的二分匹配。 这会失败，因为具有许多重复值的最坏情况多重集会强制进行太多兼容性检查，并且一般匹配速度太慢。 

当本地选择阻止未来配对时，就会出现天真的贪婪匹配的微妙失败情况。 例如，如果我们总是首先对看起来相同的值进行配对而不考虑全局频率约束，那么即使存在有效的完全匹配，我们也可能会陷入困境。 

核心困难是全局性的：在两个多重集中出现过于频繁的值可能会“消耗”太多配对机会，使得以后无法避免配对相同的值。 

## 方法

 蛮力的观点是将其视为二分图问题。 我们有$n$左边的节点（元素$s$） 和$n$在右边（元素$t$）。 每对$(x, y)$是允许的，除非$x = y$。 我们想要完美的搭配。 

一个简单的解决方案是构建完整的图并运行最大二分匹配算法。 该图很稠密，几乎存在所有边，因此复杂度大致为$O(n^2)$在最坏的情况下进行每次测试。 总共有$n$最多$2 \cdot 10^5$，这太慢了。 

关键的观察是，阻止配对的唯一因素是价值观的平等。 因此整个结构仅取决于每个值的频率计数，而不取决于位置。 如果一个值$v$在两个多重集中都出现多次，这些出现严重地相互限制，因为它们不能配对在一起。 

我们不再考虑单个元素，而是将所有内容压缩为频率计数。 对于每个值$v$， 让$a_v$算入$s$， 和$b_v$它计入$t$。 

现在考虑一下可能会出现什么问题。 如果某个特定值在两个数组中出现太多次，例如$a_v + b_v$非常大，那么大多数出现的情况必须与其他值的元素配对。 但只有$n$元素位于另一侧，因此这会产生硬容量限制。 

正确的条件很简单：对于每个值$v$，两个数组中的总出现次数不得超过$n$， 意义$a_v + b_v \le n$。 如果这适用于所有值，则始终存在有效的配对； 否则这是不可能的，因为某些值会强制进行过多的交叉配对。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力匹配|$O(n^2)$|$O(n)$| 太慢了|
 | 频率检查 |$O(n)$每次测试 |$O(n)$| 已接受 |

 ## 算法演练

 我们将问题简化为计算频率和检查简单的约束。 

1. 读取两个多重集并计算每个值的出现次数$s$和$t$。 

此步骤用频率推理代替位置推理，因为只有多重性对于配对可行性很重要。 
2. 对于每个不同的值$v$，计算总数$a_v + b_v$。 

这测量了该值在两侧出现的次数。 
3. 检查该总数是否超过$n$。 

如果是，则立即断定不存在有效的操作序列。 原因是只有$n$另一侧的元素要匹配，因此单个值的太多副本会导致不可避免的冲突。 
4. 如果没有值违反条件，则输出可能的结果。 

在这种情况下，分布足够平衡，我们总是可以安排配对，而不会被迫进行等值匹配。 

### 为什么它有效

 思考每个值$v$作为一种无法与自身配对的“类型”。 每次出现$v$在$s$必须与一些非$v$元素在$t$，反之亦然。 由于只有$n$双方的要素总数，单个值所产生的组合需求不能超过可用的匹配能力。 条件$a_v + b_v \le n$准确地防止任何值垄断太多的配对槽，这保证了始终可以安排完全匹配，避免相等的对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import Counter

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        s = list(map(int, input().split()))
        t = list(map(int, input().split()))
        
        cs = Counter(s)
        ct = Counter(t)
        
        ok = True
        for v in set(cs.keys()) | set(ct.keys()):
            if cs[v] + ct[v] > n:
                ok = False
                break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```该解决方案完全围绕频率图构建。 关键的实现选择是合并两个计数器的键集，确保任一多重集中出现的每个值都被检查一次。 尽早退出对于避免发现违规时不必要的迭代非常重要。 

该逻辑不会尝试显式地构建配对。 它仅验证可行性，这已经足够了，因为结构约束纯粹是按值计算的。

 ## 边缘情况

 关键的边缘情况是两个多重集相同并且由单个重复值组成。 例如，$s = t = [1,1,\dots,1]$。 这里条件立即失败，因为总频率是$2n$，这超过了$n$。 该算法正确地拒绝了这一点，而不尝试任何配对。 

另一种边缘情况是两个多重集之间的值完全不相交。 例如，$s = [1,2,3]$和$t = [4,5,6]$。 每个配对都是有效的，因为不会触发相等约束。 频率检查很容易通过，因为每次$a_v + b_v = 1$。 

一种更微妙的情况是，一个值在一个多重集中占主导地位，但在另一个多重集中不存在。 例如，$s = [1,1,1,1]$,$t = [2,2,2,2]$。 即使计数有偏差，每个值的总和也是准确的$n$，因此算法接受，并且存在有效的交叉配对。
