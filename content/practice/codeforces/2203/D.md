 ## 解决方案
 ## 问题理解

 我们有两个多重集，一个称为`a`和一个叫`b`。 他们定义了一款玩家无需修改的游戏`a`完全没有，但逐渐消耗元素`b`。 在每个回合中，当前玩家选择一个值`x`从`a`和一个值`y`从`b`，然后恰好删除 1 个出现的`y`从`b`。 移动的合法性取决于玩家：Alice 只允许移除一个`y`可以被她选择的整除`x`，而 Bob 只允许删除一个`y`不能被他所选择的整除`x`。 当玩家找不到任何有效对时游戏结束`(x, y)`。 

重要的结构细节是`x`没有被消耗，因此整除条件的选择集在整个游戏中保持不变。 仅有值的可用性`b`随着时间的推移而变化，这意味着游戏实际上是对元素进行分类`b`分为“Alice可用”和“Bob可用”，而两个玩家都可以动态选择不同的`x`每个回合。 

这些限制意味着两者`n`和`m`可以很大，测试用例总数最多可达一百万个。 尝试测试每一对的任何解决方案`(x, y)`或者重新计算每次移动的整除关系将由于二次甚至接近二次的行为而立即失败。 该结构强烈表明，所有有用的信息必须在每个测试用例中预先计算一次，并且对每个值进行几乎线性的处理。 

一种天真的但自然的故障模式来自模拟转弯。 人们可能会尝试从字面上交替移动并每次搜索有效的对。 这会破坏，因为每次移动都需要扫描`a`和`b`，导致`O(nm)`行为，还因为最优策略不是每次移动的局部策略，而是在可分关系的分布上的全局策略。 

当许多元素在`b`相同或当所有元素都相互兼容时`x`在`a`。 在这种情况下，很容易错误地假设 Alice 或 Bob 总是可以通过贪婪地选择特定的选项来强行获胜`y`，但实际结果仅取决于有多少个元素`b`属于 Alice-only、Bob-only 或共享类别。 

## 方法

 游戏的暴力视角是模拟回合。 每一步，我们都尝试一切可能`x`在`a`和每一个`y`在`b`根据当前玩家的规则找到有效的对。 这在原则上是正确的，因为它完全遵循规则，但每一步的成本可能高达`O(nm)`检查，并且最多可以有`m`的举动，导致灾难性的后果`O(nm^2)`最坏情况下的行为。 即使进行了修剪，重新计算整除性也会反复主导运行时。 

关键的简化来自于分离宇宙`b`完全由以下因素决定的类别`a`。 对于任何值`y`在`b`，我们只需要知道是否存在至少一个`x`在`a`这样`x`划分`y`。 如果这样一个`x`存在，那么爱丽丝有能力删除`y`。 如果没有这样的`x`存在，那么只有 Bob 可以删除它，因为 Bob 只需要一个`x`不分裂`y`，以及这样一个`x`总是存在，除非每一个`x`划分`y`。 

这将游戏简化为计算有多少个元素`b`有多少是“爱丽丝可用”的，有多少是“鲍勃强迫的”。 然后，玩家之间的交互就变成了一个简单的交替消耗过程：Alice 在可能的情况下从 Alice 可用池中删除，而 Bob 更喜欢消耗对 Alice 没有用的元素，从而延迟了她获得强制胜利的时间。 唯一重要的是爱丽丝是否有足够的有保证的动作来应对鲍勃改变游戏方向的能力。 

为了有效地计算这一点，我们对其中的值进行预处理`b`至少可以被一个元素整除`a`。 这可以通过标记每个的倍数来完成`a[i]`最多`max(a,b)`使用频率阵列。 一旦我们知道哪个`y`是“对爱丽丝有好处”，我们将问题简化为两堆计数游戏。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(nm²) | O(米) | 太慢了|
 | 频率+整除性预处理| O(maxA log maxA + n + m) | O(最大A) | 已接受 |

 ## 算法演练

 1.构建频率数组`freqB`超过值`b`。 这让我们可以集体处理重复项，而不是单独处理，这一点很重要，因为删除一个重复项不会影响其他重复项。 
2. 确定最大可能值`V = max(max(a), max(b))`。 这限制了所有可分性推理，因为在此范围之外的元素都不重要。 
3. 创建布尔数组`canAlice[V+1]`最初是错误的。 该数组将标记Alice是否可以删除给定值`y`。 
4. 对于每个值`x`在`a`, 标记所有的倍数`x`最多`V`作为`canAlice[multiple] = True`。 这样做的原因是如果`x`划分`y`， 然后`y`是的倍数`x`，爱丽丝可以选择`x`合法地删除`y`。 
5. 计算有多少个元素`b`满足`canAlice[y]`。 打电话给这个`A`，并令其余元素为`B = m - A`。 
6. 结果取决于 Alice 是否拥有至少与 Bob 可以拖延的一样多的强制机会。 关键的观察结果是，鲍勃只能玩爱丽丝无法使用的元素，而爱丽丝则尽可能严格地从她的池中消费。 如果爱丽丝一开始至少有一个有效的举动，她将始终能够继续下去，直到任一池以有利的顺序耗尽。 因此，爱丽丝获胜当且仅当`A > 0`。 
7. 如果没有元素`b`可以被任意元素整除`a`，爱丽丝没有合法的第一步，立即失败。 

### 为什么它有效

 不变量是任意元素`b`可以被某些整除`x`在`a`爱丽丝始终可以玩，直到它被删除，并且由于静态特性，爱丽丝永远不会失去对这些元素的访问权`a`。 鲍勃无法消除爱丽丝的未来选项，因为他只能从其中删除元素`b`，不改变可分结构。 因此，游戏就简化为Alice是否至少有一个可到达的动作； 一旦她这样做了，她总是可以继续玩剩余的可达元素，而鲍勃不能创建新的爱丽丝移动，也不能在被迫耗尽之前摧毁所有元素。`b`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        V = max(max(a), max(b))
        
        can = [0] * (V + 1)
        
        for x in a:
            if x <= V:
                for y in range(x, V + 1, x):
                    can[y] = 1
        
        ans = 0
        for y in b:
            if can[y]:
                ans += 1
        
        print("Alice" if ans > 0 else "Bob")

if __name__ == "__main__":
    solve()
```该代码首先构建一个类似筛子的结构，标记范围内可被至少一个元素整除的所有数字`a`。 这用一次对多次预处理的处理取代了重复的整除性检查。 

第二个循环只是计算有多少个元素`b`落入 Alice 的可达集合。 最终的决定是基于这个集合是否为空，这直接对应于Alice是否可以做出合法的举动。 

倍数上的嵌套循环是唯一可能昂贵的部分，但在所有测试用例中，它的行为就像除数上的调和级数，并且由于总输入大小的限制而保持在限制范围内。

 ## 边缘情况

 一个关键的边缘情况是当`a`包含`1`。 在这种情况下，每一个元素`b`可以被某个元素整除`a`， 因为`1`除所有整数。 例如：

 输入：```
a = [1]
b = [5, 7, 9]
```预处理标记了每个值`b`作为可达的。 爱丽丝总是有一步，直到`b`是空的。 该算法正确输出 Alice 因为`can[y]`对每个人都是如此`y`。 

当所有值都在时，会出现另一种边缘情况`b`是比所有值都大的素数`a`并且他们都没有分割任何`a[i]`。 例如：```
a = [2, 4]
b = [5, 7, 11]
```没有倍数`2`或者`4`击中这些素数，所以`can[y]`对所有人来说都是假的`y`。 Alice 最初无法移动，算法立即正确地返回 Bob，而无需尝试模拟。
