 ## 解决方案
 ## 问题理解

 该问题要求我们生成一个非负整数数组，其总和达到给定的总数`s`，附加约束是每个元素必须仅具有也在另一个数字中设置的位集`m`。 换句话说，如果某个位为零`m`，每个数组元素中它必须为零。 我们被要求找到这样一个数组中尽可能少的元素数，或者报告`-1`如果不存在数组。 

从约束条件来看，`s`和`m`可以大到$10^{18}$，并且最多可以有$10^4$测试用例。 这排除了尝试所有可能的数组或枚举每个位子集的任何暴力尝试，因为即使迭代到`s`是不可行的。 关键是在位级别上工作并推理总和如何`s`可以使用允许的二的幂来构造`m`。 

当发生微妙的边缘情况时`m`相比之下非常小`s`。 例如，如果`s = 13`和`m = 6`（二进制`110`），任何数组元素只能有`2`- 位或`4`位设置。 这些的组合不能产生`13`，所以输出是`-1`。 另一个极端情况是当`m`仅设置了一位。 为了`s = 10`和`m = 1`，唯一有效的数组是`[1,1,1,...,1]`，长度正好是`10`。 

这些例子说明可行性取决于是否`s`可以表示为两个允许的幂的总和`m`。 

## 方法

 天真的方法是尝试通过重复添加数字来构造所有数组`a_i`这样`a_i & m = a_i`，从最大可能数开始 ≤`s`。 您可以尝试所有可能的元素序列。 虽然这最终会找到一个有效的数组（如果存在），但它的速度呈指数级缓慢：每个位都可以出现在元素中，也可以不出现，最多给出 2^{\text{#bits}} 的可能性，当`s`很大。 

关键的见解是每个有效数字都是中设置的位的子集`m`。 认为`m`已在位置设置位`[b0, b1, ..., bk]`。 那么数组中的任意数字都可以写成`2^bi`对于某些索引子集。 如果我们考虑`s`在二进制中，我们可以将其视为我们需要使用这些允许的权力的无限副本来构造的目标总和。 这相当于分配设置的位`s`超过允许的位置`m`。 

最佳方法使用贪婪的位级分布。 从最低有效位开始，确定每个允许的 2 的幂需要多少个副本，总和为`s`。 中的每一位`s`可以通过分割较高位来“覆盖”`m`。 例如，如果`m`允许`4`和`2`， 和`s`有一个`6`在二进制中，我们可以将其分发为`4 + 2`。 通过对允许位的所有贡献进行求和，我们可以确定所需的最小元素数量，这对应于首先将总和分配给最大允许的幂，然后处理具有较小幂的余数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^#bits in m) | O(#bits in s) | 太慢了|
 | 最佳 | O(log s) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. Initialize a list`count`尺寸为 60（自`s`和`m`是 ≤$10^{18}$）来存储每个位可以使用多少次`m`。 迭代`m`。 对于每个位位置`i`在哪里`m`有一个`1`， 放`count[i] = 1`。 这些代表了两个人允许的权力。 
2. 迭代`s`。 对于每个位位置`i`在哪里`s`有一个`1`，尝试使用允许的位来覆盖它`count`。 如果`count[i]`已经足够了，消耗它。 如果不是，则“分解”较高位`count[j]`为了`j > i`将它们分成`2^(j-i)`一点点复制`i`。 这有效地降低了较高功率以覆盖较低功率。 
3. 如果有任何位`s`不能使用覆盖`m`的位，数组不存在，所以返回`-1`。 
4. 否则，元素的最小数量`n`等于所有的总和`1`分布式位数中的 s，表示需要多少个 2 的单独幂才能达到`s`。 
5. 返回`n`对于当前的测试用例。 

为什么它有效：不变的是每个允许的位`m`可以分解为任意数量的更小的二的幂。 这保证了我们可以表示任何不需要外部位的和`m`。 通过从高位到低位贪婪地分配，我们确保数组元素的数量最少。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s, m = map(int, input().split())
        counts = [0]*60
        for i in range(60):
            if (m >> i) & 1:
                counts[i] = 1
        need = [0]*60
        for i in range(60):
            if (s >> i) & 1:
                need[i] = 1
        # distribute higher bits down
        for i in range(59, -1, -1):
            if need[i] > counts[i]:
                if i == 0:
                    counts[i] = -1
                    break
                need[i-1] += (need[i]-counts[i])*2
        if counts[0] < 0:
            print(-1)
        else:
            total = 0
            for i in range(60):
                total += need[i]
            print(total)

solve()
```在这个实现中，`counts`跟踪哪些权力被允许`m`。 数组`need`跟踪制作所需的位数`s`。 每当较低位的要求超出可用性时，我们就会向下分配较高的功率。 如果分发失败，`-1`被打印。 否则，求和所有`need`位给出数组元素的最小数量。 

## 工作示例

 ### 示例 1：`s = 13, m = 5`二进制表示：`s = 1101`,`m = 0101`。 

| 比特| m 允许 | 的需求| 操作|
 | ---| ---| ---| ---|
 | 3 | 0 | 1 | 无法直接覆盖，尝试更高？ 没有更高，在这里失败？ |
 | 2 | 1 | 1 | 覆盖|
 | 1 | 0 | 0 | 好的 |
 | 0 | 1 | 1 | 覆盖|

 在拆分较高的允许位之后，我们可以覆盖`s = 13`带数组`[5,4,4]`给出最小长度`3`。 

### 示例 2：`s = 13, m = 6`二进制：`s = 1101`,`m = 0110`。 

无法覆盖最低位（`1`） 因为`m`有`0`一点点`0`。 分发失败，答案是`-1`。 

这些轨迹显示了位级贪婪分布如何确定可行性和最小数组长度。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(60 * t) ≈ O(t) | 我们为每个测试用例迭代 60 多个位，与`s`或者`m`。 |
 | 空间| O(60) | 位的固定大小数组； 独立于`s`或者`m`。 |

 自从`t ≤ 10^4`并且每次迭代都可以忽略不计，这在 2 秒内就可以舒适地拟合。
