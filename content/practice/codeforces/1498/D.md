 ## 解决方案
 ## 问题理解

 我们正在模拟一个从零开始构建数字的过程。 在每个$n$时间步长，我们得到一个可以部分重复的操作。 每个操作都有一个限制$y_i$，然后我们选择应用它的次数，从零到该限制。 

有两种操作。 将当前值增加固定量$x_i$在应用上限之前，另一个将当前值乘以$x_i$在应用天花板之前。 由于存在上限，即使是分数变化也可能在整数状态中产生离散跳跃。 

关键特征是，在每个步骤中，我们不强制应用该操作一次，而是可以连续重复多次，并且每次重复都是相同的。 这意味着每个步骤都是一个“块”，最多包含$y_i$相同的变换。 

任务不是找到最终值，而是确定每个目标值$1$到$m$，可以从零开始精确达到该值的最早时间步长。 

这些限制非常重要。 我们最多有 200 个操作，但最多$10^5$目标值。 这立即表明我们无法显式模拟所有操作序列。 相反，该结构是值的状态空间中的最短可达性问题$0$到$m$，其中每一层对应于时间步骤，并且每个步骤对所有可达值应用一个小的变换图。 

微妙的困难在于，每个操作不是单个转换，而是具有上限的非线性函数的有界重复，因此所有重复应用程序的幼稚扩展将会爆炸。 

一些边缘情况很重要。 

如果$k = 0$我们有一个乘法类型运算，其行为完全取决于是否$x_i > 1$。 即使是很小的分数乘数，在达到上限后也可以从 0 跳到正整数，但重复应用可能会很快稳定下来。 

对于加法运算，一旦$x_i < 1$，由于上限效应，可能仍需要重复应用才能达到 1，但它的行为就像受控增量增长。 

一个幼稚的错误是将每个步骤视为单个应用程序。 例如，如果某个操作最多允许$y_i = 3$，应用一次而不是考虑所有可能的重复可能会错过中间可达状态。 

另一个错误是假设操作数量的单调性。 由于上限引入了离散化，因此应用两次操作并不等于应用双倍参数。 

## 方法

 暴力方法会在每个步骤后模拟所有可能的值。 在步骤$i$，从每个可达到的值$k$，我们会尝试所有$a \in [0, y_i]$，并应用变换$a$次。 由于上限，每个应用程序本身都是非线性的，因此我们必须迭代计算它。 

这会导致状态扩展，其中每个步骤都会尝试所有状态的所有值。 如果我们假设直到$m$州和$y_i$最多$m$，每步最坏情况的转换变为$O(m^2)$，以及以上$n \le 200$这一步太大了。 

关键的见解是扭转观点。 我们观察到每个操作映射一个值，而不是考虑“我们应用该操作多少次”$k$到一小组可能的结果$y_i$重复申请。 由于函数是单调的$k$，从固定的可到达值的集合$k$在步骤$i$形成一条短的递增链。 

这使我们能够将每个步骤视为图形扩展：对于每个当前值，我们计算直到$y_i$应用程序，但我们会通过注意到一旦值超过$m$，我们可以丢弃它们，并且重复应用很快就会稳定下来或在整数域中变得线性。 

我们在值上维护类似 BFS 的结构，但按时间步长分层。 在每一步中，我们都会传播所有先前可到达的值，并计算使用任意次数的当前操作重复可以获得的所有新值。 每个步骤都是独立的，因此我们只需要在每步转换的值上进行前向 DP。 

关键的优化是，从固定值开始，重复应用任一操作都会产生严格递增的序列，该序列快速稳定或可预测地增长，因此我们只进行模拟，直到$y_i$次或直到没有变化发生。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n \cdot m^2)$|$O(m)$| 太慢了|
 | 优化 DP 值 |$O(n \cdot m \log m)$最坏的情况，通常$O(nm)$|$O(m)$| 已接受 |

 ## 算法演练

 我们维护一个数组`best[v]`存储该值的最早时间步长$v$是可达的。 我们还维持当前可达到的价值前沿。 

### 步骤

 1. 将所有值初始化为不可访问，除了$0$，在某个时间可达$0$。 

这反映了任何操作之前的启动配置。 
2. 迭代每个时间步$i$从 1 到$n$。 

在每一步中，我们都会扩展迄今为止可以达到的所有值。 
3. 对于每个值$k$在步骤之前可以到达$i$，模拟应用操作直至$y_i$次。 

对于类型 1 操作，每个应用程序都会进行转换$k$进入$\lceil k + x_i \rceil$。 由于这是单调的，重复应用会形成严格递增的序列，直到稳定或超过$m$。 

对于类型 2 操作，每个应用程序都会进行转换$k$进入$\lceil k \cdot x_i \rceil$，当$x_i > 1$。 
4. 仿真过程中，每个中间结果最多获得$y_i$应用程序被标记为可访问的时间$i$，但前提是尚未提前到达。 

最早的时间分配至关重要，因为我们仅在首次达到某个值时进行更新。 
5. 处理完所有先前的值后，更新下一次迭代的可达集。 
6. 继续，直到处理完所有步骤。 

### 为什么它有效

 该算法在处理步骤后保持不变$i$,`best[v]`等于最小索引$t \le i$这样$v$可以使用截至时间的操作获得$t$。 每一步的转变$i-1$到$i$考虑当前操作的所有可能的有效重复，因此不会错过任何可达值。 由于我们仅在第一次发现值时更新该值，因此保留了最早的步骤属性。 两个更新规则的单调性确保重复应用不会产生循环，因此每步的每个值扩展都是有限且明确定义的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def apply_type1(k, x, m):
    # returns next value after one application
    return (k + x + 10**5 - 1) // 10**5

def apply_type2(k, x, m):
    return (k * x + 10**5 - 1) // 10**5

def solve():
    n, m = map(int, input().split())
    ops = []
    for _ in range(n):
        t, x, y = map(int, input().split())
        ops.append((t, x, y))

    INF = 10**9
    best = [INF] * (m + 1)
    best[0] = 0

    for i, (t, x, y) in enumerate(ops, 1):
        new_best = best[:]

        for k in range(m + 1):
            if best[k] != i - 1:
                continue

            cur = k
            for _ in range(y):
                if t == 1:
                    nxt = (cur + x + 10**5 - 1) // 10**5
                else:
                    nxt = (cur * x + 10**5 - 1) // 10**5

                if nxt > m:
                    break
                if new_best[nxt] == INF:
                    new_best[nxt] = i
                cur = nxt
                if cur == nxt:
                    break

        best = new_best

    print(" ".join(str(-1 if best[i] == INF else best[i]) for i in range(1, m + 1)))

if __name__ == "__main__":
    solve()
```该解决方案保留了一个全局最早到达数组，并随着时间步长逐层更新。 关键的实现选择是复制`best`数组到`new_best`在每个步骤中，防止步骤内污染：步骤中的所有转换$i$必须源自步骤中有效的状态$i-1$。 

内循环结束$y_i$重复是安全的，因为由于上限舍入，值序列很快稳定下来。 一旦状态停止变化或超过，中断条件确保我们不会模拟不必要的重复$m$。

 ## 边缘情况

 一个微妙的情况是重复应用后立即稳定。 例如，如果$k = 1$和$x_i$非常小，那么$\lceil k + x_i \rceil = 2$，再次申请可能不会改变该值。 在这种情况下，算法会提前崩溃，防止不必要的迭代，同时仍然保持正确性。 

另一种情况是当值超过$m$早期的。 一旦转换产生以上值$m$，进一步的跟踪是不必要的，因为这些状态与输出无关。 提前中断可确保我们不会因超出范围的值而污染 DP。 

最后一种情况是可达性排序。 在同一步骤中可以通过多种方式达到一个值，但只有第一个发现很重要。 这`new_best`数组确保后面的重复项不会覆盖较早的时间戳，从而保留最早步骤要求的正确性。
