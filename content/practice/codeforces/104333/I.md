 ## 解决方案
 ## 问题理解

 我们被要求计算整数三元组$(a, b, c)$这样$a \le b \le c$，所有值都是正数，并且满足毕达哥拉斯关系$a^2 + b^2 = c^2$。 约束条件是$a$的边界是$n$，并且隐含地$b$和$c$也必须是正整数，但只能是三元组$a \le n$被视为有效的贡献。 

每个测试用例给出不同的限制$n$，对于每一个，我们必须计算存在多少个不同的毕达哥拉斯三元组，其最小边最多为$n$。 三元组计算一次，即使其斜边或第二条边超过$n$; 仅条件为$a$很重要。 

查询数量方面的限制很大，最多可达$10^5$测试用例和$n$最多$10^5$。 这种组合强制进行预处理。 每次测试$O(\sqrt{n})$或者更糟糕的是，重复时枚举仍然太慢$10^5$次。 唯一可行的方向是预先计算所有有效的三元组，一次达到最大值$n$，然后在常数时间内回答每个查询。 

一个微妙的陷阱是误解病情$a \le b \le c$。 如果在不强制排序的情况下生成所有毕达哥拉斯三元组，则排列中会出现重复项，但约束消除了歧义：每个原始几何三角形一旦排序，就会准确地贡献一种有序表示。 

另一个失败案例是多次错误地计算缩放版本。 例如，$(3,4,5)$和$(6,8,10)$两者都有效，但它们是不同的三元组，必须都计算在内。 除非明确包含缩放，否则任何仅生成原始三元组的方法都会错过有效的倍数。 

## 方法

 直接的方法是尝试每一对$(a, b)$, 计算$c = \sqrt{a^2 + b^2}$，并检查它是否是整数。 如果是这样，我们会验证订单并进行计数。 这在正确性方面是简单的，但它的表现大致如下$O(n^2)$以最坏的解释或最好的解释检查每个测试用例$O(n^2)$如果跨查询重用则总计。 和$n = 10^5$，这是远远不可能的。 

更好的观点是将几何图形与强力枚举分离。 关键的观察是，每个有效的三元组都对应于毕达哥拉斯三元组，并且可以通过迭代可能的方式生成一次边界内的所有此类三元组$a, b$在全局预计算中配对，如果$c \le 10^5$。 我们不需要对每个查询重新计算，而是一次性收集所有有效的三元组。 

自从$a^2 + b^2$增长很快，我们只需要迭代$a$最多$10^5$和$b$从$a$向上同时$a^2 + b^2 \le (10^5)^2$。 每个有效整数斜边在排序约束下恰好生成一个三元组。 

然后我们对三元组进行排序$a$，并构建一个前缀数组，我们在位置增加一个计数器$a$。 每个查询都成为前缀和查找。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$每次测试 |$O(1)$| 太慢了|
 | 最佳预计算+前缀|$O(N \sqrt{N})$|$O(N)$| 已接受 |

 ## 算法演练

 ### 预计算阶段

 1.修复全局限制$MAX = 10^5$，因为所有查询都受其限制。 
2. 迭代所有可能的情况$a$从 1 到$MAX$。 对于每个$a$, 迭代$b$从$a$向上。 

订购方式$a \le b$确保我们永远不会像这样计算重复项$(4,3,5)$分别于$(3,4,5)$。 
3. 计算$c^2 = a^2 + b^2$，然后取整数平方根$c = \lfloor \sqrt{c^2} \rfloor$。 

如果$c^2$不是完全平方数，丢弃该对。 条件$c^2 = a^2 + b^2$确保三元组有效。 
4.如果$c > MAX$，我们停止增加$b$为了这$a$，因为增加$b$只会增加$c$。 
5. 对于每个有效的三元组$(a, b, c)$，在索引处增加频率数组$a$，因为每个查询都根据最小边计算三元组。 
6. 将频率数组转换为前缀和数组，使得每个位置$n$直接给出三元组的数量$a \le n$。 

### 查询阶段

 1. 对于每个测试用例，输出索引处预先计算的前缀值$n$。 

### 为什么它有效

 每个有效的三元组都由其最小的边唯一确定$a$。 生成过程枚举所有有效对$(a, b)$和$a \le b$恰好一次，因此不会引入重复的排列。 前缀和将“具有最小边的计数三元组”精确地转换为$a$”表示成“最多计算具有最小腿的三元组$n$”，直接匹配查询需求。

 ## Python 解决方案```python
import sys
input = sys.stdin.readline

MAX = 100000

cnt = [0] * (MAX + 1)

import math

for a in range(1, MAX + 1):
    a2 = a * a
    for b in range(a, MAX + 1):
        s = a2 + b * b
        c = int(math.isqrt(s))
        if c * c == s:
            if c <= MAX:
                cnt[a] += 1
        if b > MAX or b * b > MAX * MAX:
            break

pref = [0] * (MAX + 1)
for i in range(1, MAX + 1):
    pref[i] = pref[i - 1] + cnt[i]

t = int(input())
for _ in range(t):
    n = int(input())
    print(pref[n])
```代码构建了一个全局表`cnt[a]`，它存储有多少个有效的毕达哥拉斯三元组具有最小边`a`。 嵌套循环确保顺序$a \le b$。 整数平方根检查准确验证毕达哥拉斯条件，没有浮点错误。 

这`pref`array 将其转换为累积计数，因此查询变成恒定时间查找。 当值超出全局范围时，循环内的中断条件可防止不必要的探索，从而将运行时间保持在限制范围内。 

一个微妙的细节正在使用`isqrt`，这避免了浮点平方根可能出现的精度问题。 另一个是确保只有三元组$c \le MAX$被计数，因为较大的三元组不能对任何查询做出贡献。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MAX = 100000
    cnt = [0] * (MAX + 1)
    import math

    for a in range(1, MAX + 1):
        a2 = a * a
        for b in range(a, MAX + 1):
            s = a2 + b * b
            c = math.isqrt(s)
            if c * c == s and c <= MAX:
                cnt[a] += 1

    pref = [0] * (MAX + 1)
    for i in range(1, MAX + 1):
        pref[i] = pref[i - 1] + cnt[i]

    data = inp.strip().split()
    t = int(data[0])
    idx = 1
    out = []
    for _ in range(t):
        n = int(data[idx]); idx += 1
        out.append(str(pref[n]))
    return "\n".join(out)

 ## 边缘情况

 一个重要的边缘情况是当$n < 3$。 最小的毕达哥拉斯三元组开始于$a = 3$，所以任何查询$n = 1$或者$2$必须返回零。 该算法自然地处理这个问题，因为`pref[1]`和`pref[2]`初始化后保持为零。 

另一种情况是缩放三倍，例如$(6, 8, 10)$。 枚举将在以下情况下独立检测到这一点：$a = 6$和$b = 8$。 它不依赖于生成原始三元组，因此不需要特殊处理。 

最终的结构边缘情况很大$n = 10^5$。 由于约束，内部循环提前终止$a^2 + b^2 \le MAX^2$，因此该算法避免了不必要的迭代，其中$c$会超出界限，保持运行时稳定。
