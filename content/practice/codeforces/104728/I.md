 ## 解决方案
 ## 问题理解

 我们给出了一个整数关系，其行为类似于隐藏的指数变量。 存在一定数量$x$（不一定是整数）使得其值及其倒数满足$x + \frac{1}{x} = k$， 在哪里$k$是一个至少为 2 的固定整数。根据这个隐式定义，我们需要计算表达式$x^n + x^{-n}$对于一个可能很大的指数$n$，并输出结果模$M$。 

虽然$x$其本身从未被明确知晓，该问题保证了该形式的每个值$x^n + x^{-n}$是一个整数，所以我们实际上处理的是一个由下式确定的纯整数序列$k$。 任务是评估$n$该序列的第一项有效。 

这些限制使预期的难度变得清晰。 指数$n$可以大到$10^{18}$，这排除了任何对幂进行线性迭代的方法。 任何解决方案都必须将问题简化为可以在对数时间内求幂的值，通常通过递归或矩阵求幂。 模数$M$大约是$10^9$，但它不一定是素数，因此我们不能依赖乘法逆元或域结构。 

一种直接构建权力的幼稚方法$x$是不可能的，因为$x$尚不清楚。 即使我们尝试符号计算$x^n$，我们仍然需要$O(n)$乘法。 

小尺寸时会出现微妙的边缘情况$n$。 什么时候$n = 0$，表达式变为$x^0 + x^0 = 2$，独立于$k$。 什么时候$n = 1$，就变成$x + x^{-1} = k$，直接给出。 在这些边界情况下，任何不正确的递归初始化都会失败，特别是假设单个起始值时。 

## 方法

 蛮力的观点始于这样一个事实：我们想要未知变量及其逆的重复幂。 如果我们想象分配一些数值给$x$，我们可以计算$x^n$和$x^{-n}$独立地使用快速求幂，然后将它们相加。 然而，这需要使用有理数或代数数，并且在模运算下变得不稳定，因为求逆在问题设置中没有意义。 

即使忽略表示问题，每项的直接功率计算也会花费$O(\log n)$，但由于我们仍然需要重建$x$，该方法在计算上没有明确定义。 

关键的结构见解是序列$a_n = x^n + x^{-n}$实际上并不取决于知道$x$。 扩展$a_n$使用关系$x + x^{-1} = k$，我们可以推导出线性递推：

 乘法$a_{n-1}$经过$x + x^{-1}$给出$$(x + x^{-1})(x^{n-1} + x^{-(n-1)}) = x^n + x^{-n} + x^{n-2} + x^{-(n-2)}.$$重新排列项可得到递推式：$$a_n = k a_{n-1} - a_{n-2}.$$这将问题转化为评估$n$具有常数系数的二阶线性递推的第一项。 可以使用矩阵求幂以对数时间计算此类序列，因为每个步骤仅取决于前两个值。 

我们对转换进行编码：$$\begin{pmatrix}
a_n \\
a_{n-1}
\end{pmatrix}
=
\begin{pmatrix}
k & -1 \\
1 & 0
\end{pmatrix}
\begin{pmatrix}
a_{n-1} \\
a_{n-2}
\end{pmatrix}.$$将该矩阵提升为$n-1$次方乘以基向量得出结果。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 定义不明确，有效指数 | O(1) | O(1) | 太慢了 |
 | 最优（矩阵求幂）| O(log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 定义顺序$a_n = x^n + x^{-n}$。 我们从直接替换中观察到$a_0 = 2$和$a_1 = k$。 这两个值锚定整个序列。 
2. 推导递归式$a_n = k a_{n-1} - a_{n-2}$。 这一步至关重要，因为它消除了未知变量$x$完全并将问题替换为确定性整数序列。 
3.直接处理小指数。 如果$n = 0$，返回2。如果$n = 1$， 返回$k$。 这些情况绕过矩阵求幂并防止错误访问未定义的状态。 
4. 构造转移矩阵$$T =
\begin{pmatrix}
k & -1 \\
1 & 0
\end{pmatrix}.$$该矩阵编码状态向量如何$(a_n, a_{n-1})$一步进化。 

1. 计算$T^{n-1}$使用二进制求幂。 每个平方步骤都会将指数范围减少一半，从而确保对数时间复杂度。 
2. 乘法$T^{n-1}$由基向量$(a_1, a_0) = (k, 2)$。 得到的第一个分量是$a_n$，这是所需的答案。 

### 为什么它有效

 正确性依赖于递归唯一确定一次序列的事实$a_0$和$a_1$是固定的。 转移矩阵的每次应用都保留了关系$a_n = k a_{n-1} - a_{n-2}$，因此矩阵幂对有效变换的重复应用进行编码。 由于矩阵求幂精确地模拟了重复的递归转换而无需近似，因此之后的最终状态$n-1$步骤保证等于真实的$a_n$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    M, k, n = map(int, input().split())
    k %= M

    if n == 0:
        print(2 % M)
        return
    if n == 1:
        print(k % M)
        return

    def mul(A, B):
        return [
            [(A[0][0]*B[0][0] + A[0][1]*B[1][0]) % M,
             (A[0][0]*B[0][1] + A[0][1]*B[1][1]) % M],
            [(A[1][0]*B[0][0] + A[1][1]*B[1][0]) % M,
             (A[1][0]*B[0][1] + A[1][1]*B[1][1]) % M]
        ]

    def mpow(mat, exp):
        res = [[1, 0], [0, 1]]
        while exp:
            if exp & 1:
                res = mul(res, mat)
            mat = mul(mat, mat)
            exp >>= 1
        return res

    T = [[k, (M - 1) % M], [1, 0]]
    Tn = mpow(T, n - 1)

    a1, a0 = k, 2 % M
    ans = (Tn[0][0] * a1 + Tn[0][1] * a0) % M
    print(ans)

if __name__ == "__main__":
    solve()
```代码首先标准化$k$在模数下，因为所有后续操作都以模数进行$M$。 它明确处理基本情况$n=0$和$n=1$因为矩阵公式假定起始向量包含两个连续项。 

矩阵乘法函数在模数下实现直接 2x2 乘积。 幂函数使用二进制提升，重复对转移矩阵进行平方，并在需要时将其乘以结果。 

一个微妙的实现细节是$-1 \bmod M$作为$M-1$。 这避免了模算术中的负值并保持所有计算的一致性。 最终答案是从结果状态向量的第一个分量中提取的。

 ## 边缘情况

 一个脆弱点是序列的初始化。 对于像这样的输入$k=4, n=0$，无论什么，正确的输出都是 2$k$。 该算法在任何矩阵计算之前处理此问题，并立即返回。 

另一个角落是当$k=2$。 在这种情况下，递归变为$a_n = 2a_{n-1} - a_{n-2}$，它折叠成一个常数序列。 矩阵求幂仍然有效，但轨迹显示每个状态向量在初始化后保持不变，证实了正确性。 

对于大型$n$例如$10^{18}$，没有迭代$n$被执行。 指数纯粹通过二进制分解进行处理，因此即使在极端规模下计算也保持稳定和快速。
