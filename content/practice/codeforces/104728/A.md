 ## 解决方案
 ## 问题理解

 我们从一个值开始`x = 0`并希望达到目标值`y`。 我们被允许进行两种类型的操作。 第一种类型将任意整数相加`1`到`n`到当前值。 第二种类型将当前值乘以以下值之一`m`给定乘数。 

任务是计算精确达到所需的最少操作数`y`从零开始。 

这是变相的最短路径问题。 每个整数值`x`可以看作一个节点，每个操作都定义了到其他节点的有向边。 来自任何州`x`，我们可以去`x + a`为所有人`1 ≤ a ≤ n`，并且到`x * b`对于每个乘数`b`。 

这些约束表明直接的图构造是不可能的。 目标值`y`取决于`5 × 10^6`，因此状态空间很大，但仍然足够小，可以对值进行仔细控制的 BFS。 乘法器的数量最多为 10 个，这一点至关重要，因为它可以使乘法分支保持可控。 

探索所有操作序列的简单方法随着深度呈指数级增长。 即使我们假设每个州都分支为`n + m`过渡，所需的深度可达`y`，使得暴力枚举完全不可行。 

当乘以 1 存在时，会出现微妙的边缘情况`B`。 这会产生自循环。 例如，如果`b = 1`， 然后`x → x`总是有可能的。 如果粗心的 BFS 没有正确标记访问过的状态，则可能会无限循环或无限次地重新访问状态。 

另一个边缘情况是当`n = 1`。 然后加法总是精确地递增 1，将问题简化为具有非常结构化的转换的经典最短路径。 

## 方法

 蛮力策略会将其视为未加权的图，并尝试探索来自`0`，通过重复应用加法和乘法生成所有可达值。 这在概念上是正确的，因为每个操作都有单位成本，所以我们第一次达到`y`，我们有一个最短序列。 

然而，分支因子使得这种方法爆炸。 从任何州，最多有`n + m`传出转换，以及`n`可以大到`5 × 10^6`。 即使我们将自己限制在以下值`y`，每个 BFS 步骤都需要迭代大量的添加，这是不可能的。 

关键的观察是加法运算不需要考虑所有`a`单独。 从给定的状态`x`，所有添加都会产生一系列连续的状态`x + 1`到`x + n`。 这意味着我们可以将加法视为范围放宽，而不是枚举每条边。 

这将问题转化为整数上的最短路径，我们可以跳转到`x * b`或放松一段时间间隔`[x + 1, x + n]`。 现在，该结构类似于具有优化转换的值的 BFS，其中每个状态都处理一次，并使用类似双端队列的扩展或 BFS 排序在摊销常数时间内完成松弛。 

乘法运算很少（`m ≤ 10`），因此可以明确地处理它们。 加法运算成为主要转换，但可以通过按顺序向前扩展来有效处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^y) | O(n^y) | O(y) | 太慢了 |
 | 具有优化转换的 BFS | O(y·m) | O(y) | 已接受 |

 ## 算法演练

 我们对每个值进行建模`0`到`y`作为图中的节点并使用 BFS 计算最短距离。 

1.初始化一个数组`dist`尺寸的`y + 1`将所有值设置为无穷大，并设置`dist[0] = 0`。 这表示达到每个值所需的最少操作数。 
2.推送启动状态`0`进入队列。 
3. 弹出一个值`x`从队列中。 这表示具有最小已知操作数的当前状态。 
4. 尝试所有乘法运算：对于每个`b`在`B`, 计算`nx = x * b`。 如果`nx ≤ y`和`dist[nx] > dist[x] + 1`，更新并推送`nx`进入队列。 乘法被视为直接跳转，因为它创建单个下一个状态。 
5. 通过考虑以下所有值来处理加法`x + 1`到`x + n`。 而不是迭代所有`n`每个人的可能性`x`，我们只有在第一次达到状态时才放松状态。 如果`dist[x + 1] > dist[x] + 1`，我们以类似 BFS 的受控方式向前传播。 这确保每个状态都被访问一次。 
6. 继续直到队列为空或`y`已达到。 
7. 返回`dist[y]`。 

重要的设计选择是我们从不明确枚举所有`n`每个节点的添加。 相反，每个状态最多放松一次，并且 BFS 的结构保证我们第一次达到某个值时是最优的。 

### 为什么它有效

 BFS 保证状态按照操作数递增的顺序进行处理。 每个转换的成本恰好为 1，无论是加法还是乘法。 一旦成为一个州`x`一旦最终确定（以最小距离弹出），任何未来改进它的尝试都将需要更长的路径，这与 BFS 排序相矛盾。 关键的优化是添加边形成单调前向链，因此每个节点最多插入一次，在保持正确性的同时避免冗余枚举。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

y, n, m = map(int, input().split())
B = list(map(int, input().split()))

INF = 10**18
dist = [INF] * (y + 1)
dist[0] = 0

q = deque([0])

while q:
    x = q.popleft()
    d = dist[x]

    # multiplication transitions
    for b in B:
        nx = x * b
        if nx <= y and dist[nx] > d + 1:
            dist[nx] = d + 1
            q.append(nx)

    # addition transitions
    # relax forward up to n steps
    for nx in range(x + 1, min(y + 1, x + n + 1)):
        if dist[nx] > d + 1:
            dist[nx] = d + 1
            q.append(nx)
        else:
            break

print(dist[y])
```乘法循环很简单：每个状态最多扩展到`m`如果我们找到更短的路径，我们就会放宽他们的要求。 

加法循环利用了单调性。 一旦我们达到了已经以相同或更好的成本达到的位置，该范围内的其他位置就无法通过同一层得到改善，因此我们提前停止。 这可以防止跨多个状态的大间隔的冗余扫描。

 ## 边缘情况

 当`B`包含`1`，乘法创建自循环。 例如，开始于`x = 5`, 申请`×1`产量`5`。 BFS 逻辑忽略这一点，因为`dist[5]`不会从相同的值改进，因此不会发生无限循环。 

什么时候`n = 1`，加法成为确定性链。 开始于`0`，我们只能达到`1, 2, 3, ...`。 该算法自然地处理了这一问题，因为加法循环一次仅前进一步。 

什么时候`y`很小但是`n`很大，加法循环被有效地截断`min(y, x + n)`，防止超出目标范围的不必要的探索。
