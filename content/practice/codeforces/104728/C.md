 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 的数字排列，我们希望使用一种特殊的重组操作将其转换为排序序列 1, 2, 3, ..., n。 操作很灵活：我们可以将数组切割成几个连续的片段，可以选择反转其中一些片段，然后以任意顺序重新排列这些片段，然后将它们连接回单个序列。 

成本不是整个操作本身，而是我们执行切割步骤的次数。 问题是要求所需的最小切割次数，以便在应用允许的重新排列和反转后，可以对排列进行排序。 

关键的困难在于，一旦剪切，我们就获得了很大的自由：片段可以任意反转和重新排序。 这意味着真正的约束不是关于局部交换，而是关于如何将排列分解为可以按递增顺序排列的“可逆块”。 

输入大小高达 10^6，因此任何尝试模拟操作或探索分区的解决方案都会立即变得太慢。 即使具有大量恒定开销的 O(n log n) 也可以，但对分段或贪婪尝试进行 O(n^2) 推理则不然。 

当排列已经排序或完全反转时，会出现微妙的边缘情况。 例如，如果数组已经是 [1, 2, 3, 4]，则不需要切割，如果 n = 3 时它是 [3, 2, 1]，我们可以反转整个数组并以零切割结束。 一个仅检查相邻递增游程的简单解决方案会错误地认为反转数组是“坏”的并且需要削减，但段的反转使其完全有效。 

另一个重要的场景是当排列由多个与值顺序不对齐的单调块组成时。 例如，[1, 3, 2, 4] 的行为与 [1, 2, 4, 3] 不同，尽管两者都有局部反转。 连续值的位置结构比本地排序更重要。 

## 方法

 一个蛮力的想法是尝试所有方法将排列分成段，并且对于每个分段尝试反转段的所有子集和段排序的所有排列，然后检查我们是否可以产生排序序列。 这在概念上是正确的，因为该操作明确允许这些转换。 

然而，分割成段的方式数量以 n 为指数，并且对于每个分割，重新排序的数量是段数的阶乘。 即使 n 约为 20，这也是不可行的，而当 n 达到 10^6 时，这是完全不可能的。 

关键的观察是，在我们切割之后，段的行为就像原子块一样，其内部顺序可以翻转，但其相对位置是完全灵活的。 这意味着唯一重要的是最终排序数组中应该连续的元素是否可以在不强制进行额外剪切的情况下进行分组。 

如果我们从值的位置角度来看待排列，我们可以考虑构建从 1 到 n 的排序顺序，并检查“预期的下一个值”与前一个值不相邻的次数，从而无需引入新的剪切即可修复。 每当连续性以无法通过片段内的反转来修复的方式中断时，我们就被迫引入新的剪切。 

这将问题简化为在考虑正向和反向邻接可能性时计算排列中存在多少“正确邻接结构中的连续值的段”。 

最终的结构取决于 i 和 i+1 在排列中是否以任一顺序相邻。 如果是，则它们可以属于同一段（可能是相反的）。 否则，需要一个新的段边界。

然后，我们通过合并连续整数在任一方向相邻的所有最大链来最小化切割。

 ## 算法演练

 1. 计算排列中每个值的位置。 

这让我们可以快速检查每个整数出现的位置，而无需重复扫描数组。 
2. 对于从 1 到 n−1 的每个值 i，检查 i 和 i+1 在排列中是否相邻。 

如果它们的位置相差正好 1，则认为它们相邻。 
3、如果i和i+1相邻，判断它们在数组中是按升序还是降序出现。 

两个方向都是有效的，因为我们可以反转线段。 
4. 在值 1 到 n 上构建类似图形的连接，其中如果 i 与 i+1 在数组中相邻，则它们会连接。 
5. 计算该链结构中连接组件的数量。 

每个分量对应于最大的连续整数组，在可能的反转后可以将其放置在单个段内。 
6. 答案是分量数减一，这对应于分离这些组所需的切割数。 

为什么它有效：

 排列只能在段边界处自由重新排列，但在段内，我们必须确保所有按排序顺序连续的值都可以通过向前或反向放置而相邻。 如果两个连续值在原始排列中不相邻，则在单个段内进行任何反转都无法使它们相邻而不在它们之间引入剪切。 因此，有效段精确对应于连续定位值的最大链，并且每次切割通过将一个分量分成两个来增加此类链的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    
    pos = [0] * (n + 1)
    for i, v in enumerate(p):
        pos[v] = i
    
    components = 1
    
    for i in range(1, n):
        if abs(pos[i] - pos[i + 1]) != 1:
            components += 1
    
    print(components - 1)

if __name__ == "__main__":
    solve()
```代码首先记录每个值出现的位置，因此邻接检查变为 O(1)。 然后，当排序顺序中的两个相邻值在排列中不相邻时，它会扫描连续值并增加组件计数。 每个这样的中断都表示一个必要的分割点，因为没有有效的段可以同时包含这两个值。 

最后减一将段数转换为切割数，因为 k 个段需要 k−1 次切割才能分离。

 ## 边缘情况

 对于像 [1] 这样的单元素排列，位置数组很简单，并且没有连续的对需要检查，因此组件计数保持为 1，答案变为 0。这证实了该算法正确处理简并输入，而无需尝试无效索引访问。 

对于完全排序的数组 [1, 2, 3, 4, 5]，每个连续的对在原始数组中都是相邻的，因此不会发生组件中断。 该结构仍然是单链，正如预期的那样产生零削减。 

对于完全反转的数组 [4, 3, 2, 1]，每个连续的对在位置上仍然相邻，只是方向相反。 由于邻接是由绝对位置差定义的，因此所有对都保持连接，并且算法正确地产生零切割，反映出单个反转就足够了。
