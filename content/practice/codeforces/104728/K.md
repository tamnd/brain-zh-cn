 ## 解决方案
 ## 问题理解

 我们正在处理这样的情况：$n$不同的选项，正确的答案是这些选项的一些未知的非空子集。 最初，没有选择任何选项。 在一次移动中，我们可以打开或关闭一个选项，这意味着我们可以在子集之间自由移动$n$一次翻转一个元素。 

当我们当前选择的子集与隐藏的正确子集匹配时，该过程立即停止。 由于正确的子集是未知的并且可能是任何非空子集，因此我们希望设计一系列子集状态以保证我们最终会命中每个可能的非空子集。 成本是切换操作的数量，我们感兴趣的是在最坏情况下所有可能的隐藏答案中可能的最小操作数量。 

关键的解释是我们正在构建一个在所有子集的图上的游走$n$-元素集，其中边连接仅相差一个元素的子集。 我们从空集开始，我们希望一次遍历至少访问每个非空子集一次，最小化最坏情况下的遍历长度，这相当于从空顶点开始找到覆盖这个超立方图中所有非空顶点的最短路径。 

约束条件$n \le 20$意味着最多有$2^{20}$子集，大约有一百万个。 这立即表明任何显式枚举所有子集的解决方案都是可行的，但是在更大的基数中指数或涉及所有子集的排列的任何解决方案都将太大。 然而，该结构是对称的，强烈建议采用格雷码风格的遍历而不是任意搜索。 

出现微妙的边缘情况时$n = 1$。 只有一个非空子集，因此答案只是一项操作。 另一个边缘情况是$n = 2$，其中最小遍历不是 2 而是 3，因为我们必须以覆盖从空集开始的两个单例子集的方式遍历状态。 

例如，与$n = 2$，子集是$\emptyset, \{1\}, \{2\}, \{1,2\}$。 任何从空开始的有效序列都必须注意邻接约束，并且不能在子集之间跳转。 一个天真的假设，我们可以到达所有子集$2^n - 1$步骤是错误的，因为它计算的是节点，而不是路径中的边。 

## 方法

 一个蛮力的想法是将问题建模为从空集开始搜索子集状态的所有序列，其中每一步翻转一位。 我们想要一个序列至少访问每个非空子集一次，并且我们希望最小化最坏情况下的移动总数。 这相当于找到访问一个集合中所有顶点的最短路径$n$维超立方图从$0$。 

对所有可能的行走进行简单的搜索是不可能的，因为即使限制于简单的路径，超立方体中的哈密顿路径的数量也增长得非常快。 即使生成子集的所有排列也将是以下顺序$(2^n)!$，即使对于$n = 10$。 

关键的观察是超立方体的结构允许格雷码排序。 格雷码是所有长度位掩码的序列$n$这样连续的掩码只有一位不同。 该属性与允许的操作完全匹配。 如果我们可以生成一个从空掩码开始的格雷码，那么遍历这个序列将访问所有子集，并且操作次数恰好是转换次数，即$2^n - 1$。 

更深入的见解是，我们不需要将问题视为图论意义上的“访问所有子集”。 相反，我们认识到超立方体有一条从零开始的哈密顿路径，格雷码给出了这样一条路径的显式构造。

 | --- | --- | --- | --- |

 | 格雷码构造|$O(2^n)$|$O(2^n)$或者$O(1)$仅输出 | 已接受 |

 ## 算法演练

 我们将问题转化为生成格雷码序列$n$- 位整数。 

1.从面膜开始$0$，代表没有选择的选项。 这对应于初始状态。 
2. 对于每个整数$i$从$1$到$2^n - 1$，计算格雷码值$g(i) = i \oplus (i >> 1)$。 此公式可确保连续值恰好相差一位。 
3. 跟踪连续格雷码值之间的转换。 每个转换对应于恰好切换一个选项。 
4. 计算到达每个非零子集所需的转换数量。 因为我们开始于$g(0) = 0$，操作总数是路径中的边数，即$2^n - 1$。 

因此输出直接是$2^n - 1$。 

### 为什么它有效

 全部的集合$n$位掩码形成$n$维超立方图，其中边对应于翻转一位。 格雷码排序是该图中的哈密顿路径，这意味着它在沿着有效边移动时恰好访问每个顶点一次。 由于我们从空子集开始，从 0 开始的格雷码保证每个子集都恰好遇到一次，因此每个可能的正确答案都恰好命中一次。 因此，移动次数恰好是该路径中的边数，比访问的顶点数少一。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())
print((1 << n) - 1)
```该解决方案避免显式生成子集或构造格雷码序列。 关键的减少是认识到存在最佳遍历，并且其长度纯粹由超立方体中的顶点数量决定。 

表达式$(1 << n) - 1$计算$2^n - 1$，它对应于所有非空子集。 由于最优策略对应于从空集开始的哈密顿路径，因此答案正是该路径中的转换数量。 

除了确保$n = 0$是问题约束所不允许的。 为了$n = 1$，公式正确得出$1$。 

## 工作示例

 对于$n = 2$，我们有四个子集：$00, 01, 10, 11$。 有效的格雷码序列是$00 \rightarrow 01 \rightarrow 11 \rightarrow 10$。 

| 步骤| 当前掩码| 运营|
 | --- | --- | --- |
 | 0 | 00 | 00 开始 |
 | 1 | 01 | 切换位 0 |
 | 2 | 11 | 11 切换位 1 |
 | 3 | 10 | 10 切换位 0 |

 该跟踪显示所有子集都被访问并且操作总数为 3，匹配$2^2 - 1$。 

为了$n = 3$，一种可能的序列是：$000 \rightarrow 001 \rightarrow 011 \rightarrow 010 \rightarrow 110 \rightarrow 111 \rightarrow 101 \rightarrow 100$。 

| 步骤| 当前掩码| 运营|
 | --- | --- | --- |
 | 0 | 000 | 000 开始 |
 | 1 | 001| 翻转位 0 |
 | 2 | 011| 翻转位 1 |
 | 3 | 010| 翻转位 0 |
 | 4 | 110 | 110 翻转位 2 |
 | 5 | 111 | 111 翻转位 0 |
 | 6 | 101 | 101 翻转位 1 |
 | 7 | 100 | 100 翻转位 0 |

 这证实了所有 8 个子集都在 7 次转换中被恰好访问过一次。

 ## 边缘情况

 当$n = 1$，只有一个非空子集。 从空开始，我们只需要一个开关即可到达它。 公式$2^1 - 1 = 1$直接匹配这一点，并且不存在路径歧义，因为只有一个顶点要访问。 

什么时候$n = 2$，该结构成为最小的非平凡超立方体。 天真的期望可能是两次移动就足够了，因为有两个非空子集，但邻接约束强制中间状态转换，导致总共三次移动。 格雷码结构确保所有子集仍然被最优访问，并且计算值$2^2 - 1 = 3$与所需的行程长度完全匹配。
