 ## 解决方案
 ## 问题理解

 我们得到了一系列短字符串，每个字符串代表电影中的一个场景。 我们可以从这些场景中选择一个子序列，这意味着我们保留原始顺序，但可以跳过一些场景。 

如果我们连接所选场景，我们将获得一个字符串。 目标是确定是否存在至少一个非空子序列，其连接是回文。 

关键的困难在于我们不是自由地构建字符串，而是通过选择最多三个长度的整个块，并且我们必须保持顺序。 

约束条件很大，所有测试用例的场景总数高达 100000 个。 任何尝试所有子序列的方法都是不可能的，因为子序列的数量呈指数级增长。 即使在连接后检查所有子字符串也是不可行的。 

一种幼稚的方法是尝试构建许多组合，甚至贪婪地构建回文，但在回文依赖于匹配遥远的反转模式的情况下，它会失败。 

当没有一个场景本身是回文，但两个场景组合起来形成回文时，就会出现微妙的边缘情况。 例如，“ab”和“ba”。 如果只检查单个字符串，则会错误地返回 NO。 

当回文可以由三部分组成时，就会出现另一种边缘情况：两个字母的字符串、中间的回文单字母及其反向。 例如，“ab”、“c”、“ba”。 缺少这个结构会导致错误的拒绝。 

## 方法

 强力解释将考虑场景的所有子序列，将它们连接起来，并检查生成的字符串是否是回文。 这是正确的，因为它直接遵循定义，但它探索了大小为 n 的数组的所有子集，给出了 O(2^n) 的可能性。 即使回文检查在总长度上是线性的，这也远远超出了可行的限制。 

我们需要大幅减少搜索空间。 关键的观察是回文是通过匹配两端的对称字符来确定的。 由于每个场景的长度最多为 3，因此我们只需要推理是否可以使用可用的片段形成长度为 1、2 或 3 的回文。 

这导致结构简化。 有效的子序列回文必须满足两个条件之一。 要么单个场景已经是回文串，要么我们可以选择两个场景，将其连接起来形成回文串。 由于串联必须是对称的，因此第二种情况简化为在序列中查找字符串及其相反的字符串，可能被其他元素分隔开。 

我们不需要考虑更长的组合，因为在此限制设置中任何长度大于 2 的回文都必须减少为匹配对或长度为 1 或 3 的中央回文块，并且这些已经通过检查反向和回文单数来覆盖。 

因此，这个问题变成了字符串及其逆序的频率和查找问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n·L) | O(2^n·L) | O(L) | 太慢了 |
 | 最佳 | O(n·L) | O(n·L) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例并维护一组可见的字符串。 

1. 维护迄今为止遇到的所有字符串的哈希集。 

这允许恒定时间查找反向对应项是否存在。 
2. 对于每个新字符串 s，首先检查 s 本身是否是回文。 

如果是，我们可以立即回答“是”，因为单个元素子序列是有效的。 
3. 检查是否已经看到了 s 的反转。

如果是，我们可以形成两个场景的回文串联：一个较早的字符串和当前的字符串。 
4. 此外，为了结构长度约束的安全，我们还跟踪所有看到的长度为 2 的字符串，并检查交叉匹配模式，其中一个字符串的第一个字符与另一个字符串的第二个字符以相反的顺序匹配。 然而，由于长度最多为 3，反向查找已经完全捕获了所有有效的两块回文。 
5. 如果两个条件都不满足，则将 s 插入集合中并继续。 
6. 如果最终没有条件触发，则输出NO。 

### 为什么它有效

 由整个字符串串联构建的回文必须在最终字符串上对齐对称位置。 由于每个块都很短，任何有效的构造都会折叠成单个回文块或一对顺序彼此相反的块。 反向检查保证只要子序列中存在有效的镜像对，我们就会检测到它，而不管跳过的元素如何。 

因为我们从左到右扫描，所以当我们检查候选右半部分时，每个潜在的左半部分都已经被存储，确保没有遗漏任何有效的对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_pal(s):
    return s == s[::-1]

t = int(input())
for _ in range(t):
    n = int(input())
    seen = set()
    
    ok = False
    
    for _ in range(n):
        s = input().strip()
        
        if not ok:
            if is_pal(s):
                ok = True
            else:
                rs = s[::-1]
                if rs in seen:
                    ok = True
        
        seen.add(s)
    
    print("YES" if ok else "NO")
```该解决方案为每个测试用例维护一组，并以恒定的时间平均值检查每个字符串。 

回文检查是简单的字符串反转比较。 反向查找是检测匹配伙伴是否已经较早出现的核心机制。 

布尔标志可以防止找到有效配置后不必要的工作，但不影响正确性。

 ## 边缘情况

 单字符字符串输入会立即处理，因为它始终是回文。 例如，输入`["a"]`第一步产生 YES，因为`a == a[::-1]`。 

一对像`["ab", "ba"]`只能通过反向查找来检测。 加工时`"ba"`,`"ab"`集合中已存在，即使两个字符串都不是回文，也会触发 YES 结果。 

像这样的案例`["ab", "cd", "cba"]`不会产生有效的回文子序列，因为没有反向对对齐，并且没有出现单个回文字符串。 该算法处理所有字符串，从不触发条件，并正确输出 NO。 

这些案例证实该算法纯粹依赖于结构对称性而不是暴力构造，这足以保证约束下的正确性。
