 ## 解决方案
 ## 问题理解

 给定一个非负整数数组，并且允许我们重复截断当前数组的前缀。 对于每次切割，我们计算该前缀的 MEX 并将其附加到一个新数组中。 删除该前缀后，我们继续使用剩余的后缀，直到什么都没有剩下。 自由完全在于我们如何选择这些切点。 

目标不仅仅是生成任何有效的 MEX 值序列，而是使该序列按字典顺序尽可能大。 这意味着构造的数组的第一个值尽可能大； 如果存在平局，我们将最大化第二个值，依此类推。 

所有测试用例的 n 约束总和高达 2⋅10^5，因此每个测试用例都是二次的任何解决方案都将失败。 即使 O(n log n) 解决方案也是可以接受的，但任何通过前缀从头开始重复重新计算 MEX 的方法都会太慢，因为除非经过严格优化，否则 MEX 计算本身会花费线性时间。 

一个天真的但重要的陷阱是假设我们应该始终采用完整的数组或始终采用最小的段。 例如，在像 [0, 1, 2, 0, 3] 这样的数组中，取整个数组会得到 MEX 4，这对于第一步来说是最佳的，但在其他数组中，早期切割可能会在以后产生多个大的 MEX 值。 最佳策略不是对段大小进行全局贪婪，而是对前缀在包含给定 MEX 所需的所有值方面变得“完整”时进行局部贪婪。 

当数组有许多重复的零或仅缺少一个小值时，就会出现微妙的边缘情况。 例如，[1, 1, 1] 的任何前缀都是 MEX 0，因此任何分区都会产生全零。 粗心的解决方案可能会尝试不必要地扩展段，但这并不能改善字典顺序。 

另一种边缘情况是数组已经是 [0..n-1] 的排列。 那么只有当我们取整个数组时，第一个 MEX 才是 n； 任何早期的切割都会大大减少 MEX，因此贪婪的前缀完成变得至关重要。 

## 方法

 暴力方法将模拟将数组分割成段的所有可能方法。 在每个位置，我们尝试每个可能的 k，计算前缀的 MEX，并对剩余的后缀进行递归。 计算每个前缀的 MEX 成本为 O(n)，并且每个位置有 O(n) 个选择，导致分区数量呈指数级增长。 即使记忆状态，子数组的数量也是 O(n²)，并且重新计算 MEX 使得这完全不可行。 

关键的观察结果是，前缀的 MEX 仅取决于是否存在从 0 到某个值的所有数字。 一旦我们修复了一个段，我们真正想要的是根据需要将其扩展以“收集”足够的事件，以便 MEX 变得尽可能大。 在最佳地形成一个片段后，我们将其删除并重复其余部分。 这将问题转化为贪婪扫描过程，在该过程中我们维护已经看到的值并确定何时完成完整的“MEX 块”。 

我们没有尝试所有的切割，而是从左到右扫描，逐渐收集值并跟踪当前的 MEX。 当前缀包含从 0 到当前 MEX−1 的所有数字时，我们可以关闭一个段并输出该 MEX。 然后我们重置并继续。

 ## 算法演练

 我们从左到右处理数组，同时维护当前段中数字的频率计数器和跟踪当前 MEX 候选者的变量。

1. 使用空频率表开始一个新段，并将当前 mex 设置为 0。我们正在尝试确定该段的最大可能 MEX。 
2. 逐一扫描元素，将其插入频数表中。 每次插入一个值时，我们都会更新有关存在哪些小数字的知识。 
3. 每次插入后，只要当前的 mex 值存在于频率表中，我们就将 mex 指针前移。 这确保了 mex 始终反映当前段中最小的缺失整数。 
4. 如果在任何时候我们至少看到一次从 0 到 mex−1 的所有值，我们就可以安全地关闭该段并将 mex 附加到答案中。 原因是，在不过多延迟下一个可能更大的 mex 的情况下，进一步扩展该段无法提高该位置的词典编排最优性。 
5. 将频率表和mex重置为0，并从下一个位置继续扫描。 
6. 完成数组后，如果还有未完成的段，则将其 mex 添加为最终值。 

### 为什么它有效

 每个段都被构造为使其 mex 最大化，并成为剩余数组的连续前缀。 当我们在当前段内拥有从 0 到 mex−1 的所有整数时，mex 就固定了。 进一步扩展片段只能保持mex不变或延迟下一个片段的形成，这不能改善字典顺序，因为当前mex对于最早可能的切割来说已经是最大的。 这创建了一个贪婪的不变量：每次切割都是在当前 mex 完全确定的最早位置进行，确保在最早的词典位置做出最大贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        cnt = [0] * (n + 5)
        used = set()
        res = []

        mex = 0
        have = 0

        for x in a:
            cnt[x] += 1
            used.add(x)

            while mex in used:
                mex += 1

            # we can close segment when all numbers < mex appear
            # i.e., every value 0..mex-1 is present at least once
            # we check this via cnt > 0 implicitly using mex progression
            ok = True
            for v in range(mex):
                if cnt[v] == 0:
                    ok = False
                    break

            if ok:
                res.append(mex)
                cnt = [0] * (n + 5)
                used.clear()
                mex = 0

        if mex != 0 or any(cnt):
            # recompute mex for last segment
            final_mex = 0
            while cnt[final_mex]:
                final_mex += 1
            res.append(final_mex)

        print(len(res))
        print(*res)

if __name__ == "__main__":
    solve()
```该代码维护当前段的运行频率数组和一组可见值，以有效跟踪不断变化的 mex。 mex 指针尽快贪婪地前进，并且当确认存在低于 mex 的所有值时，段被最终确定。 每次切割后重置可确保每个片段都是独立的。 

一个微妙的细节是最终的段处理：即使我们从未显式触发剪切条件，剩余的后缀仍然会贡献直接从其频率表计算出的最后一个 mex 值。

 ## 边缘情况

 考虑一个根本没有零的数组，例如 [1, 2, 3]。 任何前缀的 mex 都是 0，因此算法立即在第一个元素处关闭一个段。 生成的输出是一系列零，并且每次切割都会立即发生，因为 mex 前进的条件永远不会触发。 

对于像 [0, 0, 0] 这样的数组，只有在看到至少一个零后，mex 才会变为 1。 该段不断增长，直到出现第一个零，然后关闭，为每个段产生重复的 1。 

在 [0,1,2,3] 中，算法会等待，直到 0 到 3 的所有值都出现，然后以 mex 4 关闭一次。任何较早的切割都会在第一个位置产生较小的 mex，这会立即恶化字典顺序。
