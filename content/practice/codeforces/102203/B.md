 ## 解决方案
 ## 问题理解

 我们有一个二进制字符串描述消息接收的每一纳秒期间发生的情况。 一个`0`表示此时接收者成功收到消息，而a`1`表示干扰阻止接收。 第一个和最后一个位置保证是`0`，所以消息有一个公认的开始和结束。 

对于每个查询值`k`，允许接收器遇到干扰的时间严格小于`k`连续纳秒。 如果某个干扰块包含`k`或更连续的`1`s，消息无法完整接收。 我们需要回答对于每个给定值是否可以接收整个字符串`k`。 

输入包含字符串长度`n`, 查询数量`m`，二进制字符串本身，然后`m`的值`k`。 每条输出线是`YES`当每个连续的块`1`s 的长度小于`k`， 和`NO`否则。 

字符串的长度可以达到`10^6`，而查询数量可以达到`3 \cdot 10^5`。 这立即排除了对每个查询进行字符串的完整扫描。 这种方法的执行效果可达`10^6 * 3 * 10^5 = 3 * 10^11`字符检查，这远远超出了一秒的限制。 我们需要在一次遍历字符串的过程中提取与每个查询相关的所有信息。 

边缘情况来自于条件的严格不平等。 例如，考虑```
2 2
00
1
2
```根本没有干扰位置，因此两个查询都必须产生`YES`。 一种粗心的解决方案，寻找积极的差距，并将缺席的比赛视为人们可能错误拒绝的长度`k = 1`。 

另一个边界情况是```
4 3
0110
1
2
3
```最长的干扰块有长度`2`，所以输出是```
NO
NO
YES
```第二个查询被拒绝，因为规则要求游程长度严格小于`k`。 解决方案使用`run <= k`会错误打印`YES`为了`k = 2`。 

第三个有用的例子是```
3 2
010
1
2
```每一块`1`s 的长度正好`1`，所以答案是```
NO
YES
```再次，`k = 1`甚至不允许有一个纳秒的噪音。 

## 方法

 直接的解决方案是独立处理每个查询。 对于一个特定的`k`，扫描字符串，同时保持当前连续的个数`1`s。 如果这个数字达到`k`，答案立即`NO`; 如果扫描完成，答案是`YES`。 这是正确的，因为唯一可以使查询无效的是足够长的连续干扰块。 

问题是重复扫描。 在最坏的情况下，字符串有`10^6`字符并且有`3 \cdot 10^5`查询。 如果每个查询都需要检查整个字符串，那么最坏的情况大约是`3 \cdot 10^11`运营。 虽然每次扫描都很简单，但在时间限制下重复这么多次是不可能的。 

关键的观察是所有查询都针对同一字符串提出相同的问题。 我们不需要分别知道每个查询的所有运行的长度。 让`mx`是最长连续块的长度`1`s 在整个字符串中。 其他每个块都不长于`mx`，因此查询恰好在以下时间成功`mx < k`。 

因此整个字符串可以用一个整数来概括。 我们发现`mx`一旦进入`O(n)`时间，然后每个查询都会通过一次比较得到回答`O(1)`时间。 

暴力方法之所以有效，是因为它直接检查每个可能的障碍`k`，但它失败了，因为阻塞实际上并不依赖于`k`。 观察到最长的噪声块完全决定了每个查询，从而将问题从重复扫描字符串减少为一次预处理，然后进行恒定时间查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(nm)`|`O(1)`| 太慢了 |
 | 最佳|`O(n + m)`|`O(1)`除了输入存储之外| 已接受 |

 ## 算法演练

 1. 阅读`n`,`m`，以及二进制字符串`s`。 该字符串包含确定最差干扰周期所需的所有信息。 
2. 扫描`s`从左到右同时保持`cur`，当前连续块的长度`1`s。 当当前字符为`1`, 增量`cur`。 当它是`0`，当前的噪声块已经结束，所以重置`cur`为零。 
3. 在同一次扫描期间，保持`mx`，最大的值`cur`曾经达到过。 这是接收器受到连续干扰的最长时期。 
4. 阅读每个查询`k`并将其与`mx`。 打印`YES`恰好在什么时候`mx < k`，因为允许的连续噪声纳秒数严格小于`k`。 
5. 收集答案并一起打印。 当最多有 1 个输出字符串时，构建一个输出字符串可以避免不必要的重复输出操作`3 \cdot 10^5`查询。 

### 为什么它有效

 价值`mx`是任意连续块的最大长度`1`s。 有值的查询`k`当没有干扰块具有长度时精确有效`k`或更多。 自从`mx`是最大的此类块，所有块的长度都小于`k`恰好在什么时候`mx < k`。 预处理计算真实的最大值，因此比较可以独立地为每个查询提供正确的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    s = input().strip()

    mx = 0
    cur = 0

    for ch in s:
        if ch == '1':
            cur += 1
            if cur > mx:
                mx = cur
        else:
            cur = 0

    ans = []

    for _ in range(m):
        k = int(input())
        if mx < k:
            ans.append("YES")
        else:
            ans.append("NO")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```扫描使用`cur`代表当前运行的干扰。 仅增加它`1`并将其重置为`0`使每个连续运行独立于其他运行。 每当`cur`变得大于`mx`，我们更新全局最大值。 

对比是故意的`mx < k`， 不是`mx <= k`。 该语句允许严格少于`k`连续的嘈杂纳秒。 对于最大运行长度`3`,`k = 3`必须产生`NO`， 尽管`k = 4`产生`YES`。 

保证的第一个和最后一个字符是`0`，但算法并不依赖于此来保证正确性。 它还会正确处理包含一系列的字符串`1`s 在任一边界处。 

不存在整数溢出问题，因为最大计数器仅`n`, 至多`10^6`，Python 无论如何都会直接处理它。 字符串本身存储一次，答案列表最多包含`3 \cdot 10^5`短字符串。

 ### 示例 1

 该语句的示例有一个七个字符的消息，其中包含三个连续的噪声位置。 我们可以将其表示为`0111000`，带有查询`1`,`4`， 和`3`。

```这个例子具体说明了为什么比较必须严格。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(n + m)`| 字符串被扫描一次，每次查询都需要恒定的时间。 |
 | 空间|`O(n + m)`| 存储输入字符串和收集的输出； 算法本身使用`O(1)`辅助状态。 |

 和`n <= 10^6`和`m <= 3 \cdot 10^5`，该算法执行大约一百万个字符操作，然后最多进行三十万次比较。 与预期的规模不同，这完全在预期范围之内。`O(nm)`蛮力方法。 

## 测试用例```python
import sys
import io

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())
    s = input().strip()

    mx = 0
    cur = 0

    for ch in s:
        if ch == '1':
            cur += 1
            mx = max(mx, cur)
        else:
            cur = 0

    ans = []
    for _ in range(m):
        k = int(input())
        ans.append("YES" if mx < k else "NO")

    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample, whose string is 0111000 according to the statement's description.
assert run(
    "7 3\n"
    "0111000\n"
    "1\n"
    "4\n"
    "3\n"
) == "NO\nYES\nNO", "sample 1"

# Minimum-size string, with no interference.
assert run(
    "2 3\n"
    "00\n"
    "1\n"
    "2\n"
    "100\n"
) == "YES\nYES\nYES", "minimum size and all zeros"

# One noisy position, testing the exact boundary mx == k.
assert run(
    "3 3\n"
    "010\n"
    "1\n"
    "2\n"
    "3\n"
) == "NO\nYES\nYES", "single noisy position"

# Several runs, with the longest one in the middle.
assert run(
    "9 4\n"
    "011011110\n"
    "1\n"
    "4\n"
    "5\n"
    "6\n"

 ## 边缘情况

 全零情况通过离开来处理`mx`在整个扫描过程中等于零。 对于输入```
2 2
00
1
2
```该算法永远不会递增`cur`， 所以`mx = 0`。 两个都`0 < 1`和`0 < 2`是真实的，产生`YES`对于这两个查询。 这避免了发明不存在的噪声块。 

精确边界情况通过严格比较来处理。 为了```
4 3
0110
1
2
3
```扫描发现`mx = 2`。 查询`k = 1`失败，`k = 2`也失败了，因为`2`并不严格小于`2`， 和`k = 3`成功了。 输出是```
NO
NO
YES
```具有单一噪声位置的情况，```
3 2
010
1
2
```产生`mx = 1`。 限制为`1`是不够的，因为该条件需要少于一个连续的噪声纳秒，而限制`2`允许长度为一的游程。 输出是`NO`其次是`YES`。 

多个分离的噪声块不需要单独的查询处理。 为了```
9 4
011011110
1
4
5
6
```游程长度是`2`,`1`， 和`4`， 所以`mx = 4`。 前两个查询失败，而`4 < 5`和`4 < 6`成功。 该算法无需存储各个游程长度即可达到相同的结果，因为只有它们的最大值才能影响任何查询。
