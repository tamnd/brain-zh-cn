 ## 解决方案
 ## 问题理解

 我们有一个未知数组 (s_1,s_2,\ldots,s_n)。 该数组在某个位置之前严格递增，然后严格递减，因此它具有单个峰值。 所有的价值观都是不同的。 我们知道 (n) 和目标值 (k)，交互式判断让我们询问任意索引 (i) 的值。 任务是找到一个其值恰好为 (k) 的索引。 

数组本身不可用于程序。 每个数组访问都是一个交互式查询，写为`? i`，法官回答为（s_i）。 一旦确定了所需的索引，程序就会打印`! i`并终止。 

边界 (n\le 2\cdot10^5) 立即排除了扫描数组的可能性。 尽管普通 (O(n)) 算法在许多非交互式问题中足够小，但这里每个数组访问都是一个昂贵的查询，并且只有 80 个可用查询。 我们需要对数行为。 由于 (\log_2(2\cdot10^5)<18)，即使是几个二分搜索也能轻松满足查询限制。 

这些值本身在 0 到 (10^9) 之间，因此普通的 Python 整数就足够了。 目标肯定会出现，因此在正确识别增加和减少部分后，两个二分查找之一必须找到它。 

有几种边界情况可能会破坏粗心的实现。 考虑`n = 2`，有值`[5, 3]`和`k = 3`。 峰值位于第一个位置，因此递减部分包含索引 2 处的答案。假设峰值始终是内部元素的实现可能会丢失这种情况，并且永远不会正确搜索第二个位置。 

另一种情况是`[1, 5, 3]`和`k = 1`。 答案是第一个元素，它正好位于增加部分的左边界处。 错误地初始化其下限的二分搜索可能会丢弃它。 

相似地，`[1, 5, 3]`和`k = 3`测试递减部分的右边界。 答案是索引 3，因此递减二分查找必须允许其最终端点。 

测试“全相等”数组的请求不能从字面上得到满足，因为原始问题保证所有 (s_i) 都是不同的。 一个数组，例如`[5, 5, 5]`不是合法的输入。 最接近的有意义的测试是严格单调数组，其中峰值位于端点之一，例如`[1, 2, 3, 4]`或者`[4, 3, 2, 1]`。 

## 方法

 直接的方法是查询从 1 到 (n) 的位置，直到找到值 (k)。 它是正确的，因为每个位置最终都会被检查，并且答案保证存在。 它的问题是查询预算。 在最坏的情况下，它需要（n）个查询，最多可以达到（200,000）个，而法官只允许80个。问题不仅仅是运行时间，而是超出了交互协议的限制。 

数组的结构为我们提供了比任意数组更多的信息。 在增加的部分，如果(s_i<k)，目标只能在右边。 如果(s_i>k)，则只能向左。 在下降部分，方向相反。 因此，一旦我们知道峰值在哪里，问题就变成了两个普通的二分搜索。 

我们还可以通过二分查找找到峰值。 假设我们查询中间位置（m）并将（s_m）与（s_{m+1}）进行比较。 如果 (s_m<s_{m+1})，我们仍然处于增加的一侧，因此峰值严格位于 (m) 的右侧。 如果 (s_m>s_{m+1})，我们已经处于下降的一侧，因此峰值位于 (m) 或其左侧的某个位置。 

这给出了峰值的对数搜索。 之后，我们对递增段和递减段进行二分搜索。 查询总数最多大约为 (3\log_2 n)，远低于 (n\le2\cdot10^5) 的 80。 

暴力方法之所以有效，是因为每个位置都经过显式检查，但会失败，因为每次检查仅消耗 80 个查询中的一个。 山形排序让我们可以用二元决策替换这些单独的检查，从而将搜索从 (O(n)) 查询减少到 (O(\log n))。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(n)) 查询 | (O(1)) | (O(1)) | 太慢了|
 | 查找峰值 + 两次二分搜索 | (O(\log n)) 查询 | (O(\log n)) 缓存值，或 (O(1)) 辅助空间 | 已接受 |

 ## 算法演练

 1. 阅读(n)和(k)。 我们还不知道任何数组值，因此算法需要的每个值都必须通过交互式查询来获取。 
2.定义一个打印的查询函数`? i`，立即刷新输出，读取法官的答案，然后返回。 刷新是强制性的，因为否则判断可能会等待仍在 Python 输出缓冲区中的查询。 
3. 通过二分查找找到峰值。 维持一个范围`[lo, hi]`保证包含一个峰值。 尽管`lo < hi`， 拿`mid = (lo + hi) // 2`并查询`s[mid]`和`s[mid + 1]`。 
4. 如果`s[mid] < s[mid + 1]`，序列仍在增加`mid`，因此峰值必须严格位于右侧。 放`lo = mid + 1`。 
5. 否则，`s[mid] > s[mid + 1]`，因为所有值都是不同的。 该序列已经开始减少，因此峰值位于`mid`或向左。 放`hi = mid`。 
6. 什么时候`lo == hi`，该指数即为峰值。 该数组现在被分成一个递增的段`[1, peak]`和递减的部分`[peak + 1, n]`。 
7. 二分查找`[1, peak]`作为一个递增数组。 在位置`mid`，如果它的值小于`k`，向右移动。 如果它大于`k`，向左移动。 如果它等于`k`，立即输出该索引。 
8. 如果第一次查找失败，则进行二分查找`[peak + 1, n]`作为递减数组。 这里比较方向相反。 如果`s[mid] > k`，向右移动，因为值向右变小。 如果`s[mid] < k`，向左移动。 
9. 找到目标后，打印`! index`并终止。 (k) 发生的保证意味着如果第一次搜索没有找到，第二次搜索最终将找到它。 

### 为什么它有效

 峰值搜索不变量是当前区间始终包含最大元素。 如果`s[mid] < s[mid+1]`，最大值不能等于或之前`mid`，因为序列在那里仍在上升，所以移动到`[mid+1, hi]`保留不变量。 如果`s[mid] > s[mid+1]`，序列开始下降`mid+1`，所以最大值出现在`mid`或者更早的时候，保留不变量`[lo, mid]`。 

已知峰值后，其左侧的每个索引都属于严格递增序列，右侧的每个索引都属于严格递减序列。 相应的二分搜索准确地保留了 (k) 仍然可能出现的那些索引。 由于保证目标存在，因此这些搜索之一会到达其索引。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    cache = {}

    def ask(i):
        if i not in cache:
            print("?", i, flush=True)
            value = int(input())
            if value == -1:
                sys.exit(0)
            cache[i] = value
        return cache[i]

    # Find the peak.
    lo, hi = 1, n
    while lo < hi:
        mid = (lo + hi) // 2
        left = ask(mid)
        right = ask(mid + 1)

        if left < right:
            lo = mid + 1
        else:
            hi = mid

    peak = lo

    # Binary search on the increasing part [1, peak].
    lo, hi = 1, peak
    while lo <= hi:
        mid = (lo + hi) // 2
        value = ask(mid)

        if value == k:
            print("!", mid, flush=True)
            return
        if value < k:
            lo = mid + 1
        else:
            hi = mid - 1

    # Binary search on the decreasing part [peak + 1, n].
    lo, hi = peak + 1, n
    while lo <= hi:
        mid = (lo + hi) // 2
        value = ask(mid)

        if value == k:
            print("!", mid, flush=True)
            return
        if value > k:
            lo = mid + 1
        else:
            hi = mid - 1

if __name__ == "__main__":
    solve()
```这`ask`function是唯一与法官沟通的地方。 缓存很有用，因为峰值检测可能会查询稍后的二分搜索再次需要的位置。 重用答案可以避免在同一索引上花费另一个交互式查询。 

峰值搜索使用`lo = mid + 1`什么时候`s[mid] < s[mid + 1]`， 因为`mid`在那种情况下，它本身不可能达到顶峰。 在另一个分店，`mid`仍然是一个可能的峰值，所以正确的更新是`hi = mid`， 不是`mid - 1`。 

递增二分查找使用通常的比较规则。 递减搜索会反转方向，因为向右移动会使值变小。 

Python 这里不存在整数溢出问题，并且`(lo + hi) // 2`对于给定的边界是安全的。 关键的实施细节是`flush=True`关于每个查询和最终答案。 如果没有刷新，原本正确的交互算法可能会失败，因为法官永远不会收到请求。 

这`-1`处理是交互式法官的一种传统防御措施，它使用否定响应来表示无效查询或协议失败。 原始语句不需要使用这样的响应来有效执行，但是当它出现时终止可以防止程序继续执行无意义的输入。 

该代码适用于原始交互式判断。 普通的批处理程序无法直接执行，因为法官负责回答`? i`。

## 测试用例

 由于原始任务是交互式的，通常`run(input) -> output`单元测试模式不能直接应用。 测试工具必须通过提供请求的索引值来模拟判断。 以下测试使用相同算法的批处理版本，其中隐藏数组对测试代码显式可用。 这也使得断言具有确定性。```python
import io
import sys

def find_target(a, k):
    n = len(a)
    queries = 0

    def ask(i):
        nonlocal queries
        queries += 1
        return a[i - 1]

    lo, hi = 1, n

    while lo < hi:
        mid = (lo + hi) // 2
        left = ask(mid)
        right = ask(mid + 1)

        if left < right:
            lo = mid + 1
        else:
            hi = mid

    peak = lo

    lo, hi = 1, peak
    while lo <= hi:
        mid = (lo + hi) // 2
        value = ask(mid)

        if value == k:
            return mid, queries
        if value < k:
            lo = mid + 1
        else:
            hi = mid - 1

    lo, hi = peak + 1, n
    while lo <= hi:
        mid = (lo + hi) // 2
        value = ask(mid)

        if value == k:
            return mid, queries
        if value > k:
            lo = mid + 1
        else:
            hi = mid - 1

    raise AssertionError("Target is guaranteed to exist")

# Provided sample.
assert find_target([1, 3, 10, 8, 2], 3)[0] == 2

# Minimum-size input, peak at the first position.
assert find_target([5, 3], 3)[0] == 2

# Minimum-size input, peak at the second position.
assert find_target([3, 5], 3)[0] == 1

# Target is exactly the peak.

# Target is at the right boundary.
assert find_target([1, 5, 8, 6, 3], 3)[0] == 5

# Strictly increasing array, peak at the right boundary.

# Strictly decreasing array, peak at the left boundary.

# Large legal instance.
a = list(range(100000))

## 边缘情况

 对于第一个位置的峰值，考虑`n = 2`,`k = 3`，以及隐藏数组`[5, 3]`。 在峰值检测期间，比较位置 1 和 2 给出`5 > 3`，因此峰值范围变为`[1, 1]`。 递增搜索检查位置 1 并失败，因为其值为 5。然后递减搜索检查位置 2 并找到 3，产生`! 2`。 这种情况之所以有效，是因为允许峰值间隔直接折叠到左端点。 

对于最后位置的峰值，请考虑`[3, 5]`和`k = 3`。 比较`3 < 5`将峰值搜索移动到位置 2。递增搜索覆盖两个位置并在位置 1 找到目标。递减段不需要包含任何元素。 这验证了使用`[peak + 1, n]`用于第二次搜索，而不是强制使用无效范围。 

对于等于峰值的目标，请考虑`[1, 4, 9, 7, 2]`和`k = 9`。 峰值检测识别位置 3。递增二分搜索包括峰值本身，查询位置 3，并立即返回它。 从第一次二分搜索中排除峰值将是不必要且可能不正确的边界更改。 

对于最右侧位置的目标，请考虑`[1, 5, 8, 6, 3]`和`k = 3`。 峰值位于位置 3，因此递减搜索涵盖`[4, 5]`。 查询位置 5 返回 3。搜索必须使用`hi = n`包容性，否则最终索引处的目标将被默默丢弃。 

对于完全递增的数组，例如`[1, 2, 3, 4, 5]`，峰值位于位置 5。峰值检测期间的每次比较都会发现`s[mid] < s[mid+1]`，因此下界向右移动，直到达到 5。然后第一个二分查找将覆盖整个数组。 这是合法的，因为定义允许转折点为 (n)。 

对于完全递减的数组，例如`[5, 4, 3, 2, 1]`，峰值为位置 1。每次峰值比较都会发现`s[mid] > s[mid+1]`，因此上界向左移动，直到达到 1。递增部分仅包含位置 1，递减搜索处理位置 2 到 5。这是对称边界情况。 

最后，不能像可能那样处理重复值。 例如，`[1, 4, 4, 2]`将使位置 2 和 3 之间的比较相等，但问题禁止这样的数组。 峰值搜索依赖于这样一个事实：每次比较都是严格递增或递减的。 在实现中添加相等分支可以解决不同的问题，但这里没有必要。
