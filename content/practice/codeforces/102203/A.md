 ## 解决方案
 ## 问题理解

 我们有两份关于交货的二进制报告`n`行星。 对于每个行星，第一份报告告诉我们是否有两种类型的 kryt 都被传送到那里。 第二份报告告诉我们那里是否至少有一种。 

我们需要第三个二进制报告，其中位置`i`是`1`恰好在这个星球接收一种 kryt 但不是同时接收两种 kryt 的时候。 换句话说，我们需要区分仅接收一种类型的行星与接收两种类型或不接收两种类型的行星。 

对于单个行星，设两个实际交付指标为`a`和`b`。 第一份报告包含`a AND b`，而第二个包含`a OR b`。 期望值为`1`当正好是其中之一时`a`和`b`是`1`，这正是异或运算。 自从`a AND b`第一份报告已经给出了`a OR b`到了第二个，期望值就是`S1[i] XOR S2[i]`。 

约束条件`n <= 10^5`意味着输入本身仅包含大约`10^5`字符，因此处理每个位置一次的算法很容易足够快。 具有二次工作的算法已经可以执行大约`10^10`操作以最大尺寸进行，并且不符合一秒的限制。 指数算法远远超出了可行范围。 

第一个边缘情况是一颗不提供任何类型的行星。 例如，```
1
0
0
```答案是`0`。 将第二份报告的零解释为以某种方式表明存在差异的粗心方法是错误的，因为根本没有交付。 

第二个边缘情况是一个同时提供两种类型的行星：```
1
1
1
```答案又是`0`。 第一份报告已经告诉我们这两种类型都存在，因此该行星一定不会出现在所要求的报告中。 仅使用第二个报告会错误地生成`1`。 

第三个有用的情况是具有不同情况的相邻位置：```
4
0101
1111
```答案是`1010`。 在报告不同的位置，仅传递一种类型。 在他们同意的位置，要么两种类型都交付，要么两种类型都不交付。 

## 方法

 一个完全强力的解决方案可以想象所有可能的两种类型的交付配置`n`行星。 每个行星有两个二元决策，因此有`2^(2n) = 4^n`可能的配置。 对于每个配置，我们可以构建它的两个报告，将它们与输入进行比较，如果匹配则输出相应的答案。 这在逻辑上是正确的，因为它考虑了每个可能的底层交付分配，但在`n = 10^5`配置数量为`4^100000`，大得难以理解。 

蛮力之所以有效，是因为它搜索了可能的传递状态的整个空间，但这种搜索是不必要的，因为每个行星都是独立于其他行星的。 我们不需要重建实际的两个交付集。 对于一个位置，第一个报告表示两个交付位是否同时`1`，第二个表示是否至少有一个`1`。 这两条信息完全决定了其中是否存在一个。 

关键的观察是`S1[i]`是`a AND b`和`S2[i]`是`a OR b`。 正是其中之一`a`和`b`当这两个值不同时正是如此。 因此每个位置的答案都是`S1[i] XOR S2[i]`。 我们可以扫描这两个字符串一次并逐个字符地生成答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(4^n) | O(4^n) | O(n) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读`n`和两个二进制字符串`S1`和`S2`。 索引处的每个字符`i`两份报告中都描述了同一颗行星。 
2. 创建一个空结果字符串。 我们将为每个行星添加一个字符，因此结果将准确无误`n`人物。 
3. 对于每个位置`i`从`0`通过`n - 1`， 比较`S1[i]`和`S2[i]`。 如果相等，则追加`0`。 如果不同，请追加`1`。 

原因是相等意味着要么两种类型都被传递，要么两种类型都不被传递。 差异意味着一份报告说“两者”，而另一份报告说“至少一种”，这种情况只有在交付恰好一种类型时才会发生。 
4. 打印生成的二进制字符串。 

### 为什么它有效

 对于每一个行星，让`a`和`b`表示是否交付两种类型的 kryt。 第一份报告包含`a AND b`，第二个包含`a OR b`。 如果两者都`a`和`b`均为零，则两个报告值均为零。 如果两者均为 1，则两个报告值均为 1。 如果恰好 1 为 1，则 AND 值为 0，OR 值为 1。 因此期望的答案是`1`正是当两个报告字符不同时，这正是`S1[i] XOR S2[i]`。 由于这种推理对于每个位置都是独立的，因此完整构造的字符串是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s1 = input().strip()
    s2 = input().strip()

    ans = ''.join('1' if a != b else '0' for a, b in zip(s1, s2))
    print(ans)

if __name__ == "__main__":
    solve()
```前三个输入操作读取行星数量和两个报告。`strip()`删除换行符而不更改任何有意义的二进制字符。 

这`zip(s1, s2)`表达式按位置对报告位置进行配对。 对于每一对，条件表达式产生`1`当字符不同并且`0`当它们相等时，精确地对二进制字符执行异或。 

使用`join`有效地构建整个答案字符串。 不需要整数转换、位掩码或显式索引，并且除了两个字符串都有长度之外，没有边界计算`n`。 

变量`n`被读取是因为它是输入格式的一部分，尽管构造本身可以安全地依赖于具有所需长度的两个字符串。 Python 整数在这里不存在溢出问题，并且该算法仅执行线性工作。

 ## 边缘情况

 未交付的情况由等零表示。 例如，```
1
0
0
```在唯一的位置上，`S1[0]`和`S2[0]`相等，因此算法附加`0`。 输出是`0`，正确表明两种类型均未交付。 

两种情况用相同的表示：```
1
1
1
```这里两个报告再次一致，因此算法产生`0`。 第一份报告称两种类型都存在，而第二份报告则确认至少存在一种。 由于请求的报告仅包含具有一种类型的行星，因此必须排除该行星。 

报告不同的情况表明了积极的情况：```
1
0
1
```第一份报告称两种类型不会同时交付，而第二份报告称至少交付了一种类型。 唯一可能的情况是只传递一种类型，因此该算法比较`0`和`1`，看到差异，并输出`1`。 

最大尺寸的情况在每个位置都有相同的逻辑。 如果`n = 100000`,`S1`包括`100000`零和`S2`包括`100000`，每对都不同，所以答案是`100000`那些。 该算法对每个位置执行一次比较，并且不需要嵌套循环，因此大输入可以轻松地保持在预期的线性复杂度内。
