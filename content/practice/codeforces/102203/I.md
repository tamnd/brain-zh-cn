 ## 解决方案
 ## 问题理解

 我们从表达式开始`n × n`。 在一次迭代期间，该精确模式的每次出现都被替换为`n`号码的副本`n`。 这些副本从左到右配对，`×`插入每对内。 在连续的配对之间，以及最后一对和未配对的决赛之间`n`什么时候`n`是奇数，普通乘法符号`·`已插入。 

重复操作`k`次。 最后，剩下的每一个`×`也改为`·`，因此两个乘法符号之间的区别消失了。 任务是计算最终表达式中的所有乘法符号，模`998244353`。 

值为`n <= 10^9`和`k <= 10^6`。 即使是线性算法`k`仅执行约一百万次迭代，这是完全合理的。 不可能的是构造表达式本身，因为它的大小随着迭代次数呈指数增长。 自从`n`已经可以是十亿了，一次展开就可以创造出一个巨大的表达式，而且对于大的`k`它的大小远远超出了任何实际的内存或时间限制。 

有几个小情况直接复发很容易出问题。 为了`n = 1, k = 1`，初始的`1 × 1`变得只是`1`，所以答案是`0`。 盲目地假设每次迭代都会创建新的乘法符号的递归将错误地保留初始符号。 为了`n = 2`，表达式`2 × 2`转变为`(2 × 2)`，因此乘法符号的数量保持等于`1`永远。 这是几何比率变为的特殊情况`1`。 最后，当`k = 0`，根本没有发生任何变换，所以对于每个`n`答案正是`1`。 例如，`1 0`有答案`1`，即使第一个变换会完全删除乘法。 

## 方法

 最直接的方法是在每次迭代后构造表达式。 它是正确的，因为它遵循字面定义，替换当前的每个`n × n`并插入所需的括号和乘号。 问题在于所涉及的数据量。 让`q = floor(n / 2)`。 每次出现`×`准确地产生`q`新出现的`×`在下一次迭代中，因为`n`新的数字形式`q`完整的对。 从一开始`×`， 后`t`迭代有`q^t`这样的符号。 因此，基于构造的解决方案至少需要`Theta(q^k)`只是用来表示相关符号。 对于诸如以下的值`n = 10^9`和`k = 10^6`，这是完全不可行的。 

关键的观察是我们永远不需要实际的表达。 我们只需要知道它包含多少个乘法符号即可。 假设有`x_t`的出现次数`×`后`t`迭代。 它们中的每一个都独立地成为一个包含`floor(n / 2)`新的`×`符号。 因此`x_t = floor(n / 2)^t`。 

现在考虑总数`a_t`乘法符号，同时计数`×`和`·`， 后`t`迭代。 一旧`×`被替换为包含的表达式`n - 1`乘法符号。 在替换之前，该位置包含一个符号，因此总数正好增加`n - 2`。 

迭代时`t`， 有`x_t`出现可替换的情况。 最后，`a_{t+1} = a_t + (n - 2) x_t`和`a_0 = 1`。 

替代`x_t = q^t`给出`a_k = 1 + (n - 2)(1 + q + q^2 + ... + q^(k-1))`。 

最终替换为`×`经过`·`不改变符号的数量，所以`a_k`正是所要求的答案。 

因此我们只需要几何级数。 自从`q <= 5 * 10^8`，它小于模数`998244353`。 如果`q != 1`，我们可以使用`1 + q + ... + q^(k-1) = (q^k - 1) / (q - 1)`,

 使用模逆。 分母为零对模进行模的唯一情况是`q = 1`，这意味着`n = 2`。 在这种情况下，总和就是`k`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`Theta(floor(n/2)^k)`|`Theta(floor(n/2)^k)`| 太慢了|
 | 最佳|`O(log k)`|`O(1)`| 已接受 |

 ## 算法演练

 1. 计算`q = n // 2`。 这是新的数量`×`一位老人产生的符号`×`在下一次迭代期间，因为`n`数字恰好包含`floor(n / 2)`完整的对。 
2.观察迭代后`t`，数量`×`符号是`q^t`。 初始表达式包含一个这样的符号，给出`x_0 = 1`，并且每次迭代都会将该计数乘以`q`。 
3. 跟踪乘法符号的总数而不是表达式本身。 更换一个`×`和`n`数字创造`n - 1`结果表达式中的乘法符号。 由于旧事件贡献了一个符号，因此净增量为`n - 2`。 
4. 将所有增量加起来`k`迭代。 答案是`1 + (n - 2) * S`，

在哪里`S = 1 + q + q^2 + ... + q^(k-1)`。 
5.如果`k = 0`， 然后`S = 0`，所以答案是`1`。 几何公式也能自然地处理这个问题。 
6. 如果`q = 1`， 使用`S = k`，因为级数的每一项都是`1`。 这恰好发生在`n = 2`。 
7. 否则计算`S = (q^k - 1) * inverse(q - 1) mod MOD`。 蟒蛇的`pow(q, k, MOD)`有效地计算模幂，费马定理给出了逆矩阵：`pow(q - 1, MOD - 2, MOD)`。 

### 为什么它有效

 中心不变量是之后`t`迭代，确切地说`q^t`的出现次数`×`存在。 每个这样的事件都是独立转换的，并且每个都准确地产生`q`新的`×`符号。 对于符号总数，每次变换的出现都从一个乘法符号变为`n - 1`乘法符号，因此它贡献了净增加`n - 2`。 总结这一贡献`1, q, ..., q^(k-1)`出现次数准确地给出了乘法符号的最终数量。 最后一次转换为`×`到`·`只改变字符，不改变计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())

    q = n // 2

    if q == 1:
        geometric_sum = k % MOD
    else:
        geometric_sum = (pow(q, k, MOD) - 1) % MOD
        geometric_sum = geometric_sum * pow(q - 1, MOD - 2, MOD) % MOD

    answer = (1 + (n - 2) * geometric_sum) % MOD
    print(answer)

if __name__ == "__main__":
    solve()
```程序首先计算`q`，由形成的完整对的数量`n`由一个替换创建的副本。 变量`geometric_sum`代表转化的数量`×`所有迭代中累积的发生次数。 

这`q == 1`分支是必要的，因为`q - 1`为零，因此模逆不存在。 为了`n = 2`，进展很简单`1 + 1 + ... + 1`。 

对于每一个其他人`n`，几何级数公式有效。 Python的三参数`pow`执行模幂计算而不构造巨大的整数`q^k`。 

表达式`(n - 2) * geometric_sum`与普通整数一样可以非常大，但 Python 可以处理任意大小的整数，并且最终的模运算给出所需的结果。 在具有固定宽度整数的语言中，应该使用足够宽的类型或减少的模来执行乘法`MOD`第一的。 

该公式还可以处理`k = 0`。 在那种情况下`pow(q, 0, MOD)`是`1`，使几何和为零，所以答案变成`1`，与未更改的初始表达式完全匹配。 

## 工作示例

 对于第一个样本，`n = 5`和`k = 0`。 

| 步骤|`n`|`q`|`k`| 几何和| 回答 |
 | --- | --- | --- | --- | --- | --- |
 | 初始| 5 | 2 | 0 | 0 | 1 |

 不执行迭代。 原表达式为`5 × 5`，恰好包含一个乘法符号。 

对于第二个样本，`n = 5`和`k = 1`。 

| 步骤|`q`|`x_t`| 添加符号| 总计 |
 | --- | --- | --- | --- | --- |
 |`t = 0`| 2 | 1 |`1 * (5 - 2) = 3`| 4 |

 第一次转型`5 × 5`进入`(5 × 5) · (5 × 5) · 5`。 有四个乘号，两个`×`符号和两个`·`符号。 复发将其视为增加`3`，从一个符号到四个符号。 

对于第三个样本，`n = 5`和`k = 2`。 

| 步骤|`q`|`x_t`| 添加符号| 总计 |
 | --- | --- | --- | --- | --- |
 | 初始| 2 | 1 | 0 | 1 |
 | 迭代 1 | 2 | 1 | 3 | 4 |
 | 迭代 2 | 2 | 2 | 6 | 10 | 10

 两人`×`第一次迭代产生的符号都在第二次迭代中扩展。 每项贡献净增`3`，因此总数变为`10`。 

几何和是`1 + 2 = 3`, 给予`1 + (5 - 2) * 3 = 10`。

def solve():
    n, k = map(int, input().split())

    q = n // 2

    if q == 1:
        geometric_sum = k % MOD
    else:
        geometric_sum = (pow(q, k, MOD) - 1) % MOD

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        from contextlib import redirect_stdout
        output = io.StringIO()
        with redirect_stdout(output):
            solve()
        return output.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        input = old_input

assert run("5 1\n") == "4", "sample 2"
assert run("5 2\n") == "10", "sample 3"

# Minimum n, no iterations
assert run("1 0\n") == "1", "initial 1 × 1"

# Minimum n, one iteration removes the only multiplication
assert run("1 1\n") == "0", "n = 1"

# n = 2 is the geometric-ratio boundary case
assert run("2 1000000\n") == "1", "q = 1"

# Even n, checking the pairing behavior
assert run("4 1\n") == "3", "n = 4, k = 1"

# Maximum-size input, verifies that no expression is constructed
def reference(n, k):
    q = n // 2
    if q == 1:
        s = k % MOD
    else:
        s = (pow(q, k, MOD) - 1) % MOD
        s = s * pow(q - 1, MOD - 2, MOD) % MOD
    return (1 + (n - 2) * s) % MOD

assert run("1000000000 1000000\n") == str(
    reference(1000000000, 1000000)
), "maximum constraints"

 ## 边缘情况

 对于`n = 1, k = 1`，我们有`q = 0`。 几何和是`1`，因为仅存在第一次迭代。 答案是`1 + (1 - 2) * 1 = 0`。 这符合以下事实：`1 × 1`变成单身`1`，不留乘号。 

为了`n = 2`，我们有`q = 1`。 每次出现`2 × 2`被另一个括号替换`2 × 2`，因此乘法符号的总数永远不会改变。 该公式使用`S = k`，但系数`n - 2`为零，给出`1`对于每一个`k`， 包括`k = 10^6`。 

为了`k = 0`，几何和不包含任何项并且为零。 答案是`1`对于每一个可能的`n`。 这是正确的结果，因为原来的`n × n`仅有一个乘法符号并且没有迭代对其进行修改。 

对于奇数`n`，最终副本`n`被留在对之外。 这不会改变新的数量`×`符号，剩下的`floor(n / 2)`。 例如，与`n = 5`，一次出现变成两次`×`符号和一个未配对的`5`。 普通的`·`结果组之间的符号已经通过用五个操作数的表达式替换一个乘法符号总共创建四个乘法符号这一事实来说明。 

对于非常大的`n`和`k`，实际表达式是天文数字般大，但递推仅取决于`q`、几何级数和净增长`n - 2`。 该实现从不存储表达式或任何与其大小成比例的数量，因此相同的恒定内存量可以处理最小和最大的输入。
