 ## 解决方案
 ## 问题理解

 我们有一个字符串`s`长度`n`。 每个子字符串都通过其位置和长度进行标识，因此包含相同字符的两次出现仍会单独考虑。 对于每个可能的长度，我们都会考虑该长度的每对子串出现次数。 如果两个字符串不同，则其中一个字符串按字典顺序较小，因此这一对为答案贡献 1。 相同的弦没有任何贡献。 

任务是计算所有长度上的所有此类对。 例如，在`abac`, 两次出现`a`是不同的子串，但它们是相等的并且彼此不形成一对。 每次出现`a`确实与出现的情况形成一对`b`或者`c`。 

长度最多为`2500`，对于二次算法来说足够小，但对于 2 秒限制内的三次算法来说不够小。 已经有大约`n² / 2`起始位置对。 为每对位置执行大量额外工作的解决方案很快就会变得太慢。 目标应该在附近`O(n²)`时间。 答案可以大到`n(n-1)(n+1) / 6`,

 这是关于`2.6 * 10^9`为了`n = 2500`，因此 32 位有符号整数是不够的。 Python 整数会自动处理这个问题。 

直接实现可能会错误处理几种边缘情况。 为了`s = "a"`，不存在两个相同长度的子串出现，所以答案是`0`。 在检查两个位置是否实际存在之前开始计数的实现可能会产生虚假对。 

为了`s = "aaa"`，答案也是`0`。 每对等长子串都由相等的字符串组成，即使出现的位置不同。 如果粗心的解决方案对不同的出现次数而不是不同的字符串进行计数，则会错误地对它们进行计数。 

为了`s = "aaaa"`，同样的问题出现在每个可能的长度上。 特别是，从位置开始的两次出现`0`和`1`对于第二次出现的可用整个长度具有相同的前缀。 答案依然存在`0`。 

为了`s = "aab"`，答案是`2`。 两次出现`a`是平等的并且不贡献任何东西，而每个`a`出现与形成一对`b`发生。 解决方案必须将平等与仅仅具有不同的起始位置区分开来。 

## 方法

 最直接的方法是枚举每个子字符串的长度，收集该长度的所有子字符串出现，并按字典顺序比较每对子字符串。 这是正确的，因为每个所需的对都属于一个长度，并且会检查该长度的每一对出现情况。 

问题在于比较的次数。 对于长度`L`， 有`n-L+1`出现次数，所以对的数量是`C(n-L+1, 2)`。 

对所有长度求和，子串比较的次数为`C(n,2) + C(n-1,2) + ... + C(2,2)`这等于`n(n-1)(n+1) / 6`。 

在`n = 2500`，这正是`2,604,166,250`比较。 即使每次词典比较都是常数时间，这也已经远远超出了极限。 逐个字符地比较字符串可能会使实际成本变得更糟。 

有用的观察是，我们实际上不需要知道两个不相等的子串中哪一个较小。 对于任何两个相同长度的不同字符串，恰好有一个较小。 我们只需要判断两个子串是否相等即可。 

考虑两个起始位置`i < j`。 从以下位置开始的后缀的最长公共前缀`i`和`j`是`LCP(i,j)`。 第二个后缀只有`n-j`个字符，所以公共前缀最多可以有长度`n-j`。 

对于每个子串长度`L <= n-j`，两个子串开始于`i`和`j`恰好相等时`L <= LCP(i,j)`。 因此，所有长度`LCP(i,j) + 1, ..., n-j`产生一对有效的，而较短的长度产生相同的子串并且没有任何贡献。 

因此，这对位置的贡献`i,j`简直就是`n-j-LCP(i,j)`。 

这将删除子字符串长度上的整个循环。 我们只需要每对起始位置的 LCP。 

LCP 值本身具有简单的动态规划递归：`LCP(i,j) = 0`如果`s[i] != s[j]`，

和`LCP(i,j) = 1 + LCP(i+1,j+1)`如果`s[i] == s[j]`。 

有`O(n²)`这样的状态。 我们可以只使用`O(n)`记忆，因为每个状态仅取决于下一个对角线，即`LCP(i+1,j+1)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n³) 子串对工作，可能是 O(n⁴) 显式字符比较 | O(n²) 或更多，具体取决于表示 | 太慢了|
 | 最佳| O(n²) | O(n) | 已接受 |

 ## 算法演练

 1. 读取字符串并让`n`是它的长度。 创建一个数组`dp`长度`n+1`。 加工过程中固定起始位置`i`,`dp[j]`将代表`LCP(i,j)`计算出该状态后。 
2. 处理起始位置`i`从`n-2`下降到`0`。 我们向后处理它们是因为`LCP(i,j)`取决于`LCP(i+1,j+1)`，属于已处理的行。 
3.对于每个固定`i`， 过程`j`从`i+1`最多`n-1`。 递增顺序是必要的。 前`dp[j+1]`被覆盖，它仍然包含`LCP(i+1,j+1)`，因此可以用来计算当前状态。 
4. 如果`s[i]`和`s[j]`不同，设定`lcp = 0`。 他们的共同前缀立即结束。 
5.如果`s[i] == s[j]`， 放`lcp = 1 + dp[j+1]`。 第一个字符匹配，删除这些字符后，我们将比较从以下位置开始的后缀`i+1`和`j+1`。 
6. 第二个子字符串出现的长度可以是`1`通过`n-j`，所以有`n-j`涉及这两个起始位置的可能的等长比较。 正是第一个`lcp`这些长度是相等的。 添加`n-j-lcp`到答案。 
7. 存储计算结果`lcp`在`dp[j]`，然后继续下一步`j`。 处理完所有起始位置对后，输出累积的答案。 

### 为什么它有效

 固定任意两个起始位置`i < j`。 由这些位置形成的每个公共长度子串对的长度最多`n-j`，因为发生开始于`j`结束于字符串的末尾。 

根据定义`LCP(i,j)`，两个子串对于每个长度都相等`LCP(i,j)`，并且对于每个更大的长度，它们都是不同的`n-j`。 每当它们不同且长度相同时，按字典顺序恰好有一个较小，因此每个这样的长度恰好贡献一对有效的对。 

因此，这对位置的贡献恰好是`n-j-LCP(i,j)`。 DP 根据递归正确计算每个所需的 LCP，并且每对起始位置仅处理一次。 将这些贡献相加就可以精确得出所需的对数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve(s):
    n = len(s)
    if n < 2:
        return 0

    # dp[j] is LCP(i, j) for the current i after it is computed.
    # Before dp[j] is overwritten, dp[j + 1] is still LCP(i + 1, j + 1).
    dp = [0] * (n + 1)
    ans = 0

    for i in range(n - 2, -1, -1):
        for j in range(i + 1, n):
            if s[i] == s[j]:
                lcp = dp[j + 1] + 1
            else:
                lcp = 0

            ans += n - j - lcp
            dp[j] = lcp

    return ans

def main():
    s = input().strip()
    print(solve(s))

if __name__ == "__main__":
    main()
```外循环处理`i`向后，以便已经计算出 LCP 递归所需的行。 内循环向前推进`j`。 这种排序是实现的一个微妙部分：如果`j`被向后处理，`dp[j+1]`已经属于当前行而不是前一行，从而破坏了重复性。 

该数组有一个额外的位置，`dp[n] = 0`。 这充当两个后缀的 LCP，其中第二个索引已移过字符串末尾。 它删除了一个特殊情况`j = n-1`。 

表达式`n-j`是可用于两个起始位置的最大公共长度。 减去 LCP 正好删除了子串相等的那些长度。 已知 LCP 后，无需进行字符比较，因为两个长度相等的不等字符串始终会恰好生成一个按字典顺序排列的对。 

答案是使用Python整数累加的，因此即使最大答案大于`2^31-1`。

 ## 边缘情况

 对于`s = "a"`，外层循环永远不会执行，因为没有起始位置对。 最初的答案是`0`，这是完全正确的。 

为了`s = "aaa"`, 考虑位置`0`和`1`。 他们的 LCP 是`2`，这也是最大可能的长度，因为位置`1`仅剩两个字符。 贡献是`2-2=0`。 职位`0`和`2`同样有`LCP=1`和最大长度`1`，给出零。 因此所有位置对贡献为零，最终答案是`0`。 

为了`s = "aaaa"`，每对都会出现相同的模式。 例如，职位`0`和`2`有`LCP=2`和`n-j=2`，所以贡献为零。 DP 自然地达到精确边界，而不需要单独的相等性检查。 

为了`s = "aab"`, 职位`0`和`2`有LCP`0`和`n-j=1`, 贡献`1`。 职位`1`和`2`做同样的事情。 职位`0`和`1`有LCP`1`和`n-j=2`，所以他们的贡献是`1`，但这需要更仔细的解释：长度为一的子字符串都是`a`并且相等，而两个子串的长度是`aa`并且无法从位置`2`; 因为第二个位置是`1`，其最大长度为`2`，子串是`aa`和`ab`，这有所不同。 因此，这一对贡献了一个。 总计为`3`， 不是`2`。 

这也说明了为什么正确的自定义测试`aab`实际上是`3`。 两人`a`出现次数对长度一无贡献，但其出现次数两次的长度是`aa`和`ab`，这是不同的。 该算法通过以下方式捕获这一点：`n-j-LCP = 2-1 = 1`。 

对于由 2499 组成的最大字符串`a`后面跟着的字符`b`, 每对`a`对于每个可用长度，位置都是相等的并且贡献为零。 每对由一个`a`位置和决赛`b`具有最大公共长度`1`和液晶聚合物`0`，所以它恰好贡献了 1。 这样的职位共有2499个，给出答案`2499`。 这种情况同时测试了最大输入大小和字符串末尾附近的最大有用 LCP 边界。
