 ## 解决方案
 ## 问题理解

 有 (n) 个不同的特工和 (m) 个不同的太空港。 每个特工必须被分配到一个太空港，并且每个太空港必须至少接收一名特工。 允许将代理分配到同一空间端口，因此任务是计算从代理集到空间端口集的所有满射函数。 

代理人是不同的。 例如，对于 (n=2) 和 (m=2)，两个有效分配是代理 1 到端口 1，代理 2 到端口 2，或者反之亦然。 因此答案是2。 

我们需要对 (998244353) 取模的答案。 (n) 和 (m) 都可以达到 250000，因此 (O(nm)) 动态规划解决方案将需要大约 (6.25\cdot10^{10}) 次运算，并且是完全不可行的。 即使 (O(m^2)) 也太大了。 由于一秒的限制，除了一个小的对数因子之外，预期的解决方案基本上需要是线性的。 

有几种边界情况，粗心的实现可能会处理不当。 如果空间端口的数量多于代理的数量，例如 (n=2,m=3)，则任何分配都无法覆盖所有三个端口，因此答案为 0。涉及阶乘或包含-排除的公式必须在进行任何除法之前处理此问题。 

当只有一个太空港时，每个特工只有一个可能的目的地。 因此 (n=5,m=1) 的答案为 1。如果实现意外地从错误的端点启动了包含-排除循环，则此处可能会产生 0。 

当(n=m)时，每个太空港必须恰好包含一个特工，所以答案是(n!)。 对于 (n=2,m=2)，给出 2。对于 (n=1,m=1)，给出 1。这种情况对于检查最终的包含-排除符号和二项式系数是否处理正确也很有用。 

## 方法

 直接的暴力解决方案可以考虑每个代理的每个可能的目的地。 每个 (n) 代理都有 (m) 个选择，因此有 (m^n) 个分配需要检查。 对于每项任务，我们都会检查是否使用了所有（m）个太空港。 在最大情况下，生成的分配数量已经是 (250000^{250000})，因此在检查成本变得重要之前，这种方法就失败了。 

暴力破解之所以有效，是因为它明确地枚举了我们想要计数的对象。 问题是这些对象大多数都是无效的，没有理由单独检查它们。 

关键的观察是“每个太空港都被使用”的条件可以通过包含-排除来处理。 从所有 (m^n) 次分配开始，不需要占用任何端口。 然后减去至少一个特定端口为空的分配。 如果两个特定端口被迫为空，则每个代理只有 (m-2) 个可能的目的地，从而给出 ((m-2)^n) 个分配。 继续这个过程会得到交替和。 

如果恰好 (k) 个太空港被选择禁止，则有 (\binom{m}{k}) 种方法来选择它们，并有 ((m-k)^n) 种分配来避免它们。 因此包含-排除给出

 [
 \sum_{k=0}^{m}(-1)^k\binom{m}{k}(m-k)^n。 
]

 当 (m>n) 时，答案立即为零。 否则，我们只需要 (m+1) 项。 每个幂都可以通过 (O(\log n)) 中的模幂计算，而所有二项式系数都可以使用阶乘和逆阶乘在线性时间内生成。 

由于模数是质数且 (m<998244353)，因此从 1 到 (m) 的每个整数都有一个模逆元。 我们预先计算阶乘和逆阶乘，然后得到

 \frac{m!}{k!(m-k)!}
 \pmod {998244353}。 
]

 一个更简单的实现从以下生成连续的二项式系数

 \binom{m}{k}\frac{m-k}{k+1}。 
]

 对于该递归，我们预先计算 (1,2,\ldots,m) 的模逆。 这使整个实现在内存中保持线性，并避免存储阶乘数组。 

比较是：

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(m^n)) | (O(n+m)) | 太慢了|
 | 包含-排除| (O(m\log n)) | (O(米)) | 已接受 |

 ## 算法演练

 1. 读(n)和(m)。 如果(m>n)，立即输出0。 特工数量不足以在每个太空港放置至少一名特工。 
2. 预先计算从 1 到 (m) 的所有整数的模逆。 由于模数是素数，因此 (i) 的倒数可以通过以下方式获得

 MOD-\left\lfloor\frac{MOD}{i}\right\rfloor
 \operatorname{inv}(MOD\bmod i)
 \pmod {MOD}。 
]

 整个数组的计算时间为 (O(m))。 

1. 从二项式系数 (\binom{m}{0}=1) 开始。 对于当前 (k)，计算

 [
 \binom{m}{k}(m-k)^n
 ]

 使用模幂。 

1. 当 (k) 为偶数时加上该项，当 (k) 为奇数时减去该项。 这正是包含-排除符号，因为选择 (k) 个禁止的太空港意味着计算避开所有这些的任务。 
2. 使用更新二项式系数

 \binom{m}{k}(m-k)\运算符名称{inv}(k+1)
 \pmod {MOD}。 
]

 这避免了为每个项单独计算阶乘。 

1. 继续执行 (k=m)，保持答案对 (998244353) 取模。 由于 (n\ge1)，(k=m) 项包含 (0^n=0)，因此它没有任何贡献。 无论如何，包括它都会使公式统一。 

### 为什么它有效

 对于空间端口的每个子集 (S)，请考虑 (S) 中的每个端口都是空的分配。 如果 (|S|=k)，每个代理正好有 (m-k) 个可用目的地，因此有 ((m-k)^n) 个这样的分配。 (S) 有 (\binom{m}{k}) 个选择。 

包含-排除添加分配以避免零指定端口，减去一个端口为空的分配，添加回两个端口为空的分配，等等。 使用每个空间端口的分配仅属于 (k=0) 项。 任何完全缺失 (r>0) 空间港的作业都会以总系数出现

 # (1-1)^r

 1.

 ]

 因此，每个无效分配都完全取消，而每个有效分配仅保留一次。 所得总和正是所需的分布数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m = map(int, input().split())

    if m > n:
        print(0)
        return

    # Modular inverses of 1..m.
    inv = [0] * (m + 1)
    if m >= 1:
        inv[1] = 1

    for i in range(2, m + 1):
        inv[i] = MOD - (MOD // i) * inv[MOD % i] % MOD

    # C(m, 0)
    comb = 1
    ans = 0

    for k in range(m):
        ways = pow(m - k, n, MOD)
        term = comb * ways % MOD

        if k & 1:
            ans -= term
        else:
            ans += term

        if ans >= MOD:
            ans -= MOD
        elif ans < 0:
            ans += MOD

        # C(m, k + 1) from C(m, k)
        comb = comb * (m - k) % MOD
        comb = comb * inv[k + 1] % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```第一个分支处理结构不可能性（m>n）。 立即返回也很有用，因为公式的其余部分只需要最多 (m) 的模逆，而无论如何都不存在有效的分布。 

逆数组使用标准素数模数递推。 表达式`MOD % i`总是小于`i`，所以在处理时已经计算了它的逆`i`。 

变量`comb`存储 (\binom{m}{k}) 的当前值。 它从 1 开始，对应于 (k=0)，并且仅在处理当前项后更新。 顺序很重要，因为当前项必须使用 (\binom{m}{k})，而不是 (\binom{m}{k+1})。 

循环停止于`range(m)`，它处理 (k=0,\ldots,m-1)。 省略的 (k=m) 项是 (0^n=0)，因为 (n\ge1)，所以省略它不会改变任何内容。 这也避免了依赖于幂实现如何处理特殊表达式 (0^n)。 

蟒蛇的`pow(base, exponent, MOD)`直接执行模幂，因此中间值永远不会变得像普通整数 (base^n) 一样大。 答案和所有二项式系数均按模减少`MOD`每次乘法之后。

import io

MOD = 998244353

def solve():
    n, m = map(int, sys.stdin.readline().split())

    if m > n:
        print(0)
        return

    inv = [0] * (m + 1)
    inv[1] = 1

    for i in range(2, m + 1):
        inv[i] = MOD - (MOD // i) * inv[MOD % i] % MOD

    comb = 1
    ans = 0

    for k in range(m):
        term = comb * pow(m - k, n, MOD) % MOD

        if k & 1:
            ans -= term
        else:
            ans += term

        ans %= MOD

        comb = comb * (m - k) % MOD
        comb = comb * inv[k + 1] % MOD

    print(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

assert run("2 2\n") == "2", "sample 1"
assert run("3 7\n") == "0", "sample 2"

# Minimum-size input
assert run("1 1\n") == "1", "single agent and single port"

# More agents than ports
# Number of onto functions from 4 agents to 2 ports:
# 2^4 - C(2,1)*1^4 = 16 - 2 = 14.
assert run("4 2\n") == "14", "four agents, two ports"

# Exactly as many agents as ports: every agent must occupy
# a different port, so the answer is 5!.
assert run("5 5\n") == "120", "equal numbers"

# Maximum-size input.
# When n == m, the answer is n! modulo MOD.
expected = 1
for x in range(1, 250001):
    expected = expected * x % MOD

 ## 边缘情况

 对于(n=2,m=3)，算法进入第一个条件，因为端口数量多于代理数量。 它打印`0`无需构造逆数组。 这是正确的结果，因为覆盖三个不同的端口需要至少三个代理。 

对于(n=5,m=1)，逆数组仅包含`inv[1]=1`。 该循环有一次迭代，对应于 (k=0)。 添加 (1^5=1)，给出正确答案`1`。 每个代理必须前往唯一可用的端口。 

对于 (n=1,m=1)，同样的计算得出 (1^1=1)。 这证实了最小可能的输入不需要通用算法之外的特殊公式。 

对于 (n=m=2)，包含-排除计算为

 #4-2

 1.

 ]

 四个无限制分配包括两个有效分配和两个代理使用相同端口的分配。 第二项恰好删除了这两个无效的分配。 

一般来说，对于 (n=m)，每个有效的分发在每个端口都只有一个代理。 代理可以任意排列，给出 (n!) 个有效分配。 包含-排除公式恰好生成该值，因此 (n=m) 边界还对交替符号和二项式递推提供了强有力的检查。 

该实现还避免了 (k=m) 处的相差一问题。 最后一项将包含 (0^n)，它为零，因为 (n\ge1)，因此仅处理 (k=0) 到 (m-1) 在数学上是完整的。
