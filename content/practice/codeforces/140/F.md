[CF 140F - 新年雪花](https://codeforces.com/problemset/problem/140/F)

 **评分：** 2600
 **标签：** 几何，排序
 **求解时间：** 1m 51s

 ## 解决方案
 ## 问题理解

 我们在平面上得到一组点，代表对称雪花部分融化后幸存的晶体。 最初，全套晶体具有中心对称性：存在某个点$C$这样对于每个晶体$P$，反映的点通过$C$，即$2C - P$，也是一块水晶。 晶体可能正好位于中心本身。 

一些晶体消失了，但最多$k$他们消失了。 幸存的点都是不同的。 我们的任务是恢复原始对称中心的每个可能位置。 

如果我们最多可以添加一个候选中心，那么该候选中心是有效的$k$丢失点，使得结果集变得围绕该中心中心对称。 

输入大小完全决定了解决方案。 我们可能有多达$2 \cdot 10^5$点，因此任何显式检查所有点对并独立验证它们的算法都是不可能的。 甚至$O(n^2)$已经意味着周围$4 \cdot 10^{10}$运营。 同时，$k$很小，最多 10 个。这种不对称性是问题的核心：几乎所有点都必须在对称性下正确匹配。 

最危险的边缘情况来自许多中心表面上看似合理的情况。 

考虑一个点：```
1 0
5 7
```每个中心都有效，因为一个幸存的点总是可以与一个缺失的点配对。 由于存在无限多个答案，因此正确的输出是：```
-1
```仅从现有点对生成中心的粗心实现会错过这一点。 

另一个棘手的情况是当几个点已经形成对称结构，但仍然存在一些不匹配的点时：```
3 1
0 0
2 0
10 0
```中心$(1,0)$是有效的。 积分$(0,0)$和$(2,0)$彼此匹配，同时$(10,0)$需要缺失点$(-8,0)$。 只允许有一个缺失点。 

幼稚的实现可能会错误地拒绝这一点，因为当前并非每个点都有合作伙伴。 

重复的候选中心是错误的另一个来源。 认为：```
4 0
0 0
0 2
2 0
2 2
```每个相对的对生成相同的中心$(1,1)$。 除非精确表示坐标，否则浮点比较可能会意外打印重复项。 

无限答案条件也很微妙，当$n \le 2k$。 如果我们允许删除或添加足够的点来独立修复每个不匹配，那么任何中心都变得可行。 例如：```
2 1
0 0
10 0
```选择任意中心$C$。 每个现有点都可以简单地声称其对称对应点融化了。 由于两点可能无法匹配并且$k=1$，存在无限多个中心。 

## 方法

 蛮力的想法很简单。 每个有效中心必须是两个幸存点的中点，或者穿过一个幸存点本身。 我们可以枚举所有$O(n^2)$中点，然后对于每个候选点检查有多少点未能找到其对称对应点。 

验证本身可以在$O(n)$使用点的哈希集。 对于一个中心$C$, 每个点$P$要求$2C-P$存在，否则该伙伴必须算在熔化的晶体中。 

问题在于候选人的数量。 有$O(n^2)$不同的中点，并验证每个镜头$O(n)$，导致$O(n^3)$时间。 即使存储所有候选人也已经不可能了$n=2 \cdot 10^5$。 

关键的观察来自于微小的值$k$。 如果至多$k$如果缺少点，那么几乎每个幸存点都必须在幸存集合中已经有其反映的伙伴。 

修复有效中心$C$。 如果一个点的反射通过$C$不存在于幸存的集合中。 每一颗缺失的水晶最多只能解释一个不良的残存点。 因为至多$k$熔化的晶体最多有$k$不好的地方。 

这意味着至少$n-k$点都是好的，并且每个好的点都参与到一个幸存的对称对中。 对于每一对这样的$(P,Q)$，中心等于它们的中点。 

现在选择任意幸存点$A$。 如果$A$很好，然后将其与其反射的伙伴配对立即显示出真正的中心。 如果$A$不好，丢弃它并尝试另一点。 由于最多有$k$坏点，其中$k+1$至少有一点必须是好的。 

这大大减少了搜索。 我们只需要检查一小组锚点和所有其他点之间形成的中点。 具体来说，取第一个$k+1$点保证至少有一个锚点参与真正的对称对。 每个anchor最多生成$n$候选中心，因此候选总数变为$O(kn)$，这是可以管理的，因为$k \le 10$。 

然后可以在线性时间内验证每个候选者。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$|$O(n^2)$| 太慢了 |
 | 最佳 |$O(k n^2)$最坏的情况，非常小的实用$k$|$O(n)$| 已接受 |

 ## 算法演练

 1. 读取所有点并将它们存储在哈希集中$O(1)$会员资格检查。 
2. 检查是否$n \le 2k$。 

在这种情况下，存在无限多个中心。 每一个幸存的点都可以简单地视为不匹配，并且每个不匹配点只消耗一颗缺失水晶。 因为至多$2k$点存在，任何中心最多可以使用$k$缺少对。 
3.选择第一个$\min(n, k+1)$点作为锚点。 

因为至多$k$对于任何有效中心来说，点都是不好的，至少有一个锚点必须是好的。 
4. 对于每个锚点$A$，将其与每个点配对$B$在集合中。 

他们的中点成为候选中心：$$C = \frac{A+B}{2}$$为了避免浮点精度问题，请存储双倍中心：$$D = (A_x + B_x,\ A_y + B_y)$$这代表$2C$。 
5. 使用集合对候选中心进行重复数据删除。 

许多不同的对生成相同的中点。 
6. 验证每个候选中心。 

对于每一点$P=(x,y)$，计算其反射点：$$P' = D - P$$其中减法是按坐标进行的。 

如果$P'$点集中不存在，则增加不匹配点的计数。 
7. 如果不匹配的点数最多为，则接受该候选人$k$。 

每个无敌残存点对应一颗熔化的水晶。 
8. 输出所有接受的中心。 

由于我们存储了双倍坐标，因此在打印时除以 2。 

### 为什么它有效

 对于任何有效的中心，至多$k$幸存点缺少幸存的反射伙伴。 其他每个点都属于一个幸存的对称对，其中点等于中心。 

其中第一$k+1$锚点，至少有一个不能差。 该好的锚点参与幸存的对称对，因此将其与反射的对应点配对会在候选枚举期间生成真实的中心。 

验证是精确的，因为当其反映的伙伴不存在时，点精确地贡献于不匹配的计数。 每个缺失的晶体都可以准确地解释一个不匹配的幸存点，因此当且仅当不匹配的计数不超过$k$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    pts = [tuple(map(int, input().split())) for _ in range(n)]
    st = set(pts)

    if n <= 2 * k:
        print(-1)
        return

    anchors = pts[:min(n, k + 1)]

    candidates = set()

    for ax, ay in anchors:
        for bx, by in pts:
            candidates.add((ax + bx, ay + by))

    ans = []

    for dx, dy in candidates:
        bad = 0

        for x, y in pts:
            rx = dx - x
            ry = dy - y

            if (rx, ry) not in st:
                bad += 1
                if bad > k:
                    break

        if bad <= k:
            ans.append((dx, dy))

    print(len(ans))

    for dx, dy in ans:
        print(dx / 2.0, dy / 2.0)

if __name__ == "__main__":
    solve()
```第一个重要的细节是无限答案条件。 如果$n \le 2k$，每个幸存的点都可能保持不匹配，并且每个不匹配的点只需要一个缺失的反射伙伴。 由于没有几何限制，因此可以有无限多个中心。 

该实现存储双中心而不是浮点坐标。 例如，通过中点计算生成的中心可以包含一半$(0.5, 1.5)$。 将其表示为$(1,3)$避免精度错误并使散列可靠。 

候选生成仅使用第一个$k+1$点作为锚点。 这是关键的优化。 一个有效的中心不能同时使所有这些锚点变坏，因为最多有$k$总共有坏点。 

在验证过程中，反映点$(x,y)$围绕双中心$(dx,dy)$简直就是$(dx-x,\ dy-y)$。 所有算术都保持整数。 

早间休息的时候`bad > k`对性能很重要。 无效的候选者通常会很快失败，因此实际运行时间远小于理论上限。

 ## 边缘情况

 再次考虑无限答案的情况：```
1 0
5 7
```该算法立即检查是否$n \le 2k$。 这里$1 \le 0$是假的，所以我们继续。 候选生成会产生无限多个概念中心，但验证表明每个中心都需要一个缺失点。 自从$k=0$，只有将点放在自身上的中心才能生存。 生成的候选正确地折叠到单个中心$(5,7)$。 

现在检查：```
2 1
0 0
10 0
```这次$2 \le 2$，所以算法打印`-1`。 任何中心都是可能的，因为两个点可能只是缺少其反映的伙伴。 

另一个微妙的情况是中心位于现有点上：```
3 0
-1 0
0 0
1 0
```有效中心是$(0,0)$。 在验证过程中，点$(0,0)$反映到自身，它存在于集合中。 该算法自然地处理这个问题，因为自我反思不需要特殊情况的逻辑。 

最后，考虑重复的中点生成：```
4 0
0 0
2 0
0 2
2 2
```几对产生双中心$(2,2)$。 候选集会自动删除它们的重复项，因此验证会运行一次，答案也会出现一次。
