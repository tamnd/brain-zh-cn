 ## 解决方案
 ## 问题理解

 我们得到了一系列栅栏板，每个栅栏板都有一个初始高度和每单位高度增加的成本。 一次操作让我们选择一块板并将其高度增加一倍，每次都支付其单位成本。 我们可以对任何板子重复此操作任意多次。 

目标是确保没有两个相邻的板最终具有相同的最终高度。 我们并不是试图匹配目标形状，只是为了避免邻居之间的平等，同时花尽可能少的钱。 

关键的困难在于我们不直接选择最终高度，我们只控制增量。 因此，每块板从其初始高度开始都有无限多个可能的最终值，并且每个额外的单元都会线性增加成本。 

这些约束强制每个查询采用 O(n) 或 O(n log n) 解决方案，因为所有查询的总 n 最多为 3×10^5。 任何尝试探索邻居之间的所有高度组合或在大值范围内使用 DP 的解决方案都会因无限制的高度增长而立即失败。 

一种天真的尝试是通过增加两块板中的一块来打破平局，从而独立地修复每个相邻的相等性。 这会失败，因为增加一块板可能会与其另一块相邻板产生新​​的冲突，因此本地修复无法安全地组合。 

第二个微妙的边缘情况是三个连续的板具有相同的初始高度。 仅贪婪地修复中间部分可能看起来是最佳的，但可能会迫使以后重复增加，这比预先调整不同的配置更昂贵。 

## 方法

 如果我们将每个板重新解释为具有两种可能的“状态”（相对于我们在最终配置中增加的数量），问题就会变得容易处理。 由于只有邻居之间的平等才重要，所以重要的不是绝对高度，而是两个相邻的选定的最终高度是否发生碰撞。 

关键的观察是，在最佳解决方案中，每块板最多比其原始值增加两倍。 这一开始并不明显，但从结构中可以看出：如果一个董事会被提出两次以上，我们可以以较低的成本组合将分离的责任转移给邻居。 这将每个节点限制在一个小的状态空间中。 

因此，我们将每个位置视为最多有三个有意义的选择：将其增加 0、1 或 2 个单位。 通过在本地重新分配调整，可以更便宜地模拟任何更高的增长。 

现在问题变成了线性动态规划，在每个位置我们选择三种状态之一，并且我们支付与所选增量成比例的成本，同时确保相邻的最终高度不同。 

对于每个 i，我们尝试从 i−1 处的状态到 i 处的状态的所有转换，检查是否：

 a[i] + delta[i] != a[i−1] + delta[i−1]

 我们将成本累积为 delta[i] * b[i]。 

这将问题简化为链上的小状态 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解所有高度分配 | 指数| O(1) | O(1) | 太慢了 |
 | 每个位置有 3 个状态的 DP | 每个查询 O(n) | O(1) 额外 | 已接受 |

 ## 算法演练

 我们将 dp[j] 定义为当当前棋盘增加 j 个单位时，到达当前位置的最小成本，其中 j 为 0、1 或 2。 

我们从左到右处理板材。 

1. 初始化第一块板的 dp。 对于 {0,1,2} 中的每个 j，dp[j] = j * b[1]，因为我们只为增量付费。 
2. 对于从 2 到 n 的每个下一个板 i，创建一个初始化为无穷大的新数组 ndp。 
3. 对于 {0,1,2} 中的每个先前状态 p 和 {0,1,2} 中的当前状态 c，检查最终高度是否不同：a[i-1] + p != a[i] + c。 如果它们相等，则跳过此转换。 
4. 如果转换有效，则更新：

 ndp[c] = min(ndp[c], dp[p] + c * b[i])

这确保我们继承最便宜的有效配置。 
5. 将 dp 替换为 ndp 并继续。 
6. 处理完所有位置后，答案为min(dp[0], dp[1], dp[2])。 

为什么它有效

 DP 对相邻对的所有有效局部配置进行编码，同时保留最佳子结构。 任何全局解决方案都恰好对应于每个位置 {0,1,2} 中的一个增量序列。 如果最优解在某个位置使用了较大的增量，我们可以将其减少 3 并调整邻居而不破坏有效性，这意味着在截断的状态空间内保留了最优性。 邻接约束仅取决于最终值的相等性，因此局部兼容性完全决定了全局可行性，从而允许链DP捕获完整的解空间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    n = int(input())
    a = []
    b = []
    for _ in range(n):
        x, y = map(int, input().split())
        a.append(x)
        b.append(y)

    if n == 1:
        print(0)
        return

    dp = [0, b[0], 2 * b[0]]

    for i in range(1, n):
        ndp = [INF, INF, INF]
        for p in range(3):
            for c in range(3):
                if a[i - 1] + p == a[i] + c:
                    continue
                ndp[c] = min(ndp[c], dp[p] + c * b[i])
        dp = ndp

    print(min(dp))

q = int(input())
for _ in range(q):
    solve()
```DP 阵列跟踪当前板上每个允许增量状态的最佳成本。 该过渡明确强制相邻板之间禁止具有相同的最终高度。 成本项仅取决于我们对当前板应用多少增量，因为每个单位的成本为 b[i]。 

一个微妙的实现点是正确初始化第一个元素的 dp ； 它必须包括所有三个状态，而不仅仅是零，因为未来的过渡可能需要灵活性以避免平等。

 ## 边缘情况

 一个关键的边缘情况是所有初始高度都相等。 该算法必须避免仅仅因为它是最便宜的本地修复而重复增加同一块板。 在 DP 中，这是通过将所有三个状态向前推进来处理的； 在每一步中，明确不允许相同的最终高度，迫使算法将增量分布在多个板上，而不是堆叠在一个板上。 

另一种边缘情况是严格递增序列，其中没有两个邻居相等。 在这种情况下，每个转换都是有效的，并且 DP 正确地在各处选择零增量，因为 dp[0] 在所有位置上传播不变。 

最后的边缘情况是交替相等的对，如模式 5、5、6、6、7、7。 此处，本地修复可能会产生干扰，但 DP 会保留多个状态选择，以便早期决策不会迫使后续进行昂贵的修正。
