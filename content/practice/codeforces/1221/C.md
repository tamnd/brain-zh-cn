 ## 解决方案
 ## 问题理解

 每个查询都描述了一组分为三组的学生。 有些学生是程序员，有些学生是数学家，有些学生根本没有专业知识。 一个有效的团队必须恰好包含三名学生，并且必须包括至少一名编码员和至少一名数学家。 剩余的空缺（如果有）可以由任何学生填补，包括那些没有专业知识的学生，甚至可以通过在编码员或数学家之间复制角色类型来填补，只要满足最低要求即可。 

任务是确定对于每个查询，在这些约束下可以形成多少个不相交的三级团队。 每个学生最多只能使用一次，因此我们基本上将可用的人员划分为有效的三元组。 

约束条件达到$10^8$每个类别最多$10^4$查询。 这立即排除了对组合的任何模拟或搜索。 任何解决方案都必须将每个查询减少到恒定时间算术，因为$10^4$查询甚至$O(\sqrt{n})$或者$O(n)$每个查询都会太慢。 

当一组非常大而其他组很小时，就会出现微妙的失败案例。 例如，如果编码员很多，但数学家稀缺，我们就不能贪婪地首先使用所有编码员来组建团队，因为数学家成为瓶颈。 同样，“通用”学生（没有专业化的学生）很灵活，但不能取代每个团队至少有一名编码员和一名数学家的要求。 

一个天真的错误是假设我们应该总是贪婪地组建团队，每个团队消耗一名编码员和一名数学家，然后用中立的学生填充。 这在简单的情况下有效，但在平衡中立组的使用可以允许更有效的重新分配时失败。 

## 方法

 蛮力的想法很简单。 我们反复尝试从任何类别中挑选一名程序员、一名数学家和一名额外的学生来组建一个团队。 我们继续下去，直到无法形成有效的三元组为止。 这是正确的，因为每一步都尊重约束。 然而，每个团队的组成会根据组成减少一到两个单位的计数，所以在最坏的情况下我们会执行$O(c + m + x)$每个查询的操作。 值高达$10^8$，这是不可行的。 

关键的观察是，只有两个约束真正重要：每个团队至少需要一名编码员和至少一名数学家。 中立学生只影响核心配对确定后可以支持多少支额外队伍。 

如果我们首先将编码员和数学家配对，则此类强制配对的数量受到以下限制：$\min(c, m)$。 每个团队需要一名编码员和一名数学家，所以最多$\min(c, m)$无论学生是否中立，团队都可以存在。 然而，中立的学生可以通过填补第三个空位来间接取代缺失的角色，这可以将“不平衡”的情况转化为超出直接配对限制的额外团队。 

核心见解是每个团队恰好消耗三名学生，并且每个有效团队必须至少包括一名编码员和一名数学家。 因此，限制因素要么是程序员和数学家的数量，要么是学生总数除以三。 因此，最佳答案受以下两者限制：$$\min(c, m, \lfloor (c + m + x)/3 \rfloor)$$这个表达式捕获了两个约束：我们不能超过编码员或数学家中较小的一个，并且我们不能超过由所有学生组成的可能团队的总数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个查询 O(c + m + x) | O(1) | O(1) | 太慢了 |
 | 最佳 | 每个查询 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取数值$c, m, x$进行查询。 这些代表编码员、数学家和中立学生的数量。 
2. 计算学生总数$s = c + m + x$。 由于每个团队使用三名学生，因此这捕获了全局容量限制。 
3. 计算$s // 3$，这是如果我们忽略角色限制的话可能的最大团队数量。 这确保了我们永远不会超过可用的学生。 
4. 计算$\min(c, m)$，如果每个团队必须至少消耗一名编码员和一名数学家，则这是可能的最大团队数量。 这增强了角色的可行性。 
5. 取这两个界限的最小值。 这种交集确保同时满足两个资源约束。 
6. 输出查询结果。 

### 为什么它有效

 每个团队恰好消耗三名不同的学生，因此团队总数不能超过$s // 3$。 独立而言，每个团队至少需要一名编码员和一名数学家，因此团队数量不能超过其中之一$c$或者$m$。 中立的学生只会影响第三个位置的填补方式，但不会改变每个团队必须从两个基本池中抽取的事实。 因此，真正的最大值是这些独立约束的交集，它恰好是三个量的最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        c, m, x = map(int, input().split())
        total = c + m + x
        print(min(c, m, total // 3))

if __name__ == "__main__":
    solve()
```直接按照推导公式实现。 每个查询的唯一计算是一些算术运算，因此它以恒定的时间运行。 该划分使用整数楼层划分，它正确地强制执行完整团队的最大数量。 

一个常见的错误是试图通过首先消耗编码员和数学家，然后用中立者进行调整来贪婪地构建团队。 这种方法存在过度使用某一类别的风险，从而阻碍了以后的最佳编队。 封闭式解决方案通过将整个决策过程压缩为全局约束来避免任何排序问题。

 ## 边缘情况

 一种重要的边缘情况是所需角色之一为零。 用于输入`0 10 10`，无法组建团队，因为每个有效团队都需要至少一名编码员。 该算法计算`min(0, 10, 20//3)`正确地产生`0`。 

另一个微妙的情况是，中立的学生很多，但一个角色很小。 为了`10 1 100`，总计为 111，因此总计//3 为 37，但 min(c,m) 为 1，因此答案为 1。这证实了中立学生无法弥补缺少的所需角色。 

最后一种情况是一切都平衡的情况，例如`3 3 3`。 这里total//3等于3，min(c,m)等于3，因此所有学生都可以完美地分为大小为3的有效团队，这验证了该公式没有人为地限制对称输入。
