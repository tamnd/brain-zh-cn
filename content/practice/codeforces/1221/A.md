 ## 解决方案
 ## 问题理解

 我们有几个独立的游戏状态。 每个状态由值为 2 的幂的图块组成。 在一步操作中，我们可以选择两个具有相同值的图块，并将它们合并为一个图块，其值是它们的总和。 

问题是是否有可能获得有价值的瓷砖`2048`执行任意次数的合并后。 

操作与游戏2048中完全相同。两个相等的2的幂相结合成下一个更大的2的幂。 由于每个值都已经是 2 的幂，因此每次合并也会产生 2 的幂。 

限制非常小。 最多有 100 个查询，每个查询最多包含 100 个数字。 即使使用二的幂的频率计数进行模拟也很容易足够快。 我们不需要任何复杂的数据结构。 

关键的观察来自于了解哪些瓷砖可以为未来做出贡献`2048`。 

任何大于`2048`是没用的。 由于合并只会增加值，因此诸如`4096`永远不可能成为`2048`。 它也无法与较小的瓷砖合并来创建`2048`，因为只允许在相等的值之间进行合并。 

另一个微妙的情况是当所有可用瓷砖的总和达到`2048`，即使没有任何单个图块开始接近该值。 

例如：```
1
11
1 1 2 2 4 4 8 8 16 16 1024
```可用金额为：```
1+1+2+2+4+4+8+8+16+16+1024 = 1086
```这还不够，所以答案是`NO`。 

另一个例子：```
1
2
1024 1024
```答案是`YES`因为两个`1024`瓷砖直接合并到`2048`。 

一个常见的错误是包含大于`2048`总而言之：```
1
2
4096 4
```正确答案是`NO`。 

粗心的解决方案可能会计算出总和`4100 ≥ 2048`并错误地回答`YES`，尽管`4096`瓷砖永远无法帮助生产`2048`。 

## 方法

 最直接的方法就是模拟游戏。 我们可以计算每个 2 的幂有多少块。 每当有至少两个具有某种价值的副本时`x`，我们将它们对合并为值`2x`。 重复这个过程最终会产生所有可能创建的图块。 

该模拟是正确的，因为每个合法的合并序列都会产生完全相同的最终进位传播。 问题是它的机械量超出了我们实际需要的量。 

关键的观察是每块瓷砖的价值最多`2048`总是可以根据需要进行合并。 2 的幂的行为与二进制进位完全相同。 

假设我们取所有不超过的值`2048`并将它们加在一起。 如果它们的总和至少为`2048`，那么我们总是可以执行合并，直到`2048`出现图块。 原因是重复合并只是将总质量转换为越来越大的 2 的幂。 

如果所有瓷砖的总和不超过`2048`小于`2048`，然后创建一个`2048`平铺是不可能的，因为合并永远不会增加总和。 

这将整个问题简化为一个简单的求和。 

对于每个查询，忽略每个大于的数字`2048`，将剩余的数字相加，并检查总和是否至少为`2048`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n + log V) | O(n + log V) | O(log V) | 已接受 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 这里`V`是模拟期间可能出现的两个的最大幂。 

## 算法演练

 1.读取查询数。 
2. 对于每个查询，读取所有图块值。 
3. 将运行总和初始化为零。 
4. 对于每个图块，检查其值是否最多为`2048`。 
5. 如果该值最多为`2048`，将其添加到运行总和中。 

值大于`2048`永远无法为创造一个`2048`平铺，因此它们被忽略。 
6. 处理完所有图块后，将总和与`2048`。 
7. 如果总和至少为`2048`， 打印`"YES"`。 
8. 否则，打印`"NO"`。 

### 为什么它有效

 每次合并操作都会保留所有图块的总和。 两块相等的瓷砖`x + x`成为单个瓷砖`2x`，因此没有损失或获得任何价值。 

每块瓷砖都大于`2048`是无关紧要的，因为合并永远不会减少值。 这样的瓷砖永远不可能成为`2048`，也不能与较小的值合并来创建`2048`。 

在其值不超过的瓷砖中`2048`，重复合并的行为与二进制加法中的进位完全相同。 如果它们的总和至少为`2048`，这些进位最终产生`2048`瓦。 如果它们的总和小于`2048`，任何合并序列都不能创建其值超过可用总质量的图块。 

因此条件```
sum(all values ≤ 2048) ≥ 2048
```既是必要的又是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())

    for _ in range(q):
        n = int(input())
        arr = list(map(int, input().split()))

        total = 0
        for x in arr:
            if x <= 2048:
                total += x

        print("YES" if total >= 2048 else "NO")

solve()
```实现直接遵循证明。 

变量`total`存储可能对未来做出贡献的每个图块的总和`2048`。 任何大于的值`2048`立即被跳过。 

处理完一个查询后，通过一次比较即可确定答案。 

Python 中不存在溢出问题。 即使在最坏的情况下，总和也远低于 Python 的整数限制。 

最常见的实现错误是忘记忽略大于的值`2048`。 这样做会错误地处理瓷砖，例如`4096`作为有用的贡献者。

 ## 边缘情况

 考虑：```
1
1
2048
```该算法添加`2048`到运行总和，得到`2048`。 由于总和至少已经是`2048`，它输出`YES`。 不需要合并，因为目标图块已存在。 

现在考虑：```
1
2
4096 4
```该算法忽略了`4096`并只保留`4`。 结果总和是`4`，所以它输出`NO`。 这符合游戏规则，因为价值永远不会减少。 

最后，考虑：```
1
4
512 512 512 512
```运行总和变为`2048`。 算法输出`YES`。 

跟踪实际的合并：```
512 + 512 -> 1024
512 + 512 -> 1024
1024 + 1024 -> 2048
```这证实了该解决方案背后的关键不变量：所有可用的瓷砖都贡献其总质量来构建一个`2048`瓷砖，只有总和才重要。
