 ## 解决方案
 ## 问题理解

 我们得到了一个由道路连接的城市的加权无向图，其中每个城市最初包含一定数量的居民。 随着时间的推移，一系列城市会按顺序被“摧毁”，这意味着当一座城市在预定日期遭到袭击时，它必须不再有居民。 

居民可以随时沿着道路移动，每次移动都要支付道路的重量。 一次移动将单个居民转移到一条边上，但多个居民可以独立遍历并且可以任意重复移动，因此实际上每个居民的行为就像具有标准最短路径移动成本的图上的流动单元。 

任务是在所有时间里选择如何重新安置居民，以便每当一座城市受到攻击时，它在那一刻是空的，同时最小化总移动成本。 

重新表述这一限制的一个关键方法是，每个居民最终必须到达一个在需要撤离之前从未受到过严格攻击的城市。 由于攻击按固定顺序发生，因此一座城市在序列中最后一次发生后就变得“不安全”，因为在那之后它将再次受到攻击。 

因此，问题简化为将每个居民从其原始城市分配到某个足够安全的目的地城市，从而最小化图中的总最短路径旅行成本。 

约束多达 100,000 个节点、边和事件，因此任何重新计算每个城市或每个事件的最短路径的方法都会立即变得太慢。 即使来自每个城市的一个 Dijkstra 也会$O(n (m \log n))$，这远远超出了限制。 

一个微妙的边缘情况是对同一城市的重复攻击。 例如，如果一个城市出现多次，则只有最后一次出现才对可行性产生影响，但独立处理每次出现的简单解决方案可能会错误地过度限制分配。 

如果我们假设只有在城市受到攻击时才能转移居民，就会出现另一个失败案例。 该问题明确允许随时移动，这意味着我们可以在任何事件之前以最佳方式预先定位居民，因此与逐个事件模拟相关的解决方案将错过全局最佳交通。 

## 方法

 暴力视角是单独对待每个居民，并在所有“有效”（即到达时安全）的城市中决定其最终目的地城市。 对于每个居民，我们将计算从其出发点到每个可能目的地的最短路径，并选择最小的有效成本。 这在原则上是正确的，因为居民除了通过能力之外不会进行互动，而能力是无限的。 

然而，这变得昂贵，因为对于每个$10^5$从城市开始，我们需要完整的最短路径计算，至少导致$10^5$迪杰斯特拉运行。 即使进行优化，这也是不可能的。 

关键的见解是扭转观点。 我们可以考虑“生存足够长”的来源，并从安全城市向后传播他们的能力，而不是推动居民从他们的来源前进。 最后受到攻击的城市是最安全的，我们可以沿着最短路径逐步向后扩展安全性。 

这导致了多源最短路径过程，但具有由城市的最后出现时间引起的排序约束。 我们计算每个城市最后一次受到攻击的时间，然后按安全顺序降序处理城市。 每个城市都可以作为所有尚未“封城”的城市居民的潜在目的地。 

出现的结构是，我们想要为每个城市计算到达最后一次攻击时间足够长的任何城市的最小成本。 这成为动态增长的源集上的最短路径问题，可以使用从所有当前安全城市初始化的类似 Dijkstra 的多源传播来处理。 

一旦我们预先计算出每个城市到达任何安全目的地的最低成本，最终的答案就是该城市所有居民最佳分配成本的总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n \cdot m \log n)$|$O(n + m)$| 太慢了|
 | 最优（具有逆向安全处理的多源Dijkstra）|$O((n+m)\log n)$|$O(n+m)$| 已接受 |

 ## 算法演练

 ### 第 1 步：计算每个城市的最后攻击时间

 我们扫描攻击序列并记录每个城市出现的最后索引。 从未出现的城市被认为具有无限的安全性，因为它们从未被摧毁。 

此步骤将与时间相关的问题转化为每个城市的静态“安全水平”。 

### 第 2 步：按安全性对城市进行排序（从最安全到最不安全）

 我们将安全性定义为按降序排列的最后一个攻击位置。 我们将从最安全的城市开始，逐步“激活”城市。 

这个想法是，当一个城市变得活跃时，它可以成为不太安全城市的居民的有效目的地。 

### 步骤3：初始化多源Dijkstra结构

 我们维护一个初始化为无穷大的距离数组。 所有当前活动的安全城市都被插入到距离为 0 的优先级队列中。 

这些活跃的城市代表了居民可以安全安置而不会遭受未来袭击的目的地。 

### 步骤 4：降低城市安全门槛

 我们按照安全门槛从高到低的顺序扫描城市。 当我们将一个城市纳入活动集中时，我们将其插入距离为 0 的优先级队列中。 

从这一点来说，它可以成为其他城市放松的来源。 

这样做的原因是，一旦一个城市“足够安全”，它就可以永久容纳居民，而不会在最终毁灭时间之前被迫再次撤离。 

### 步骤 5：在整个图表上运行 Dijkstra

 我们从活动集中执行标准 Dijkstra 更新，放松边缘并在整个图表中传播最小成本值。 

每一次放松都代表着让居民走向当前安全的地区。 

### 第 6 步：提取每个城市的最终答案

 过程稳定后，每个城市都会计算出到达某个安全目的地的最低成本。 我们将此成本乘以城市居民数量，然后将所有内容相加。 

### 为什么它有效

 在任何时刻，活动集代表所有足够安全、可以作为最终目的地的城市。 由于我们按照安全性从高到低的顺序激活城市，因此一旦城市激活，它就永远不会失效。 这种单调性确保 Dijkstra 始终只探索可行的目的地。 根据最短路径成本，每个居民都被有效地分配到最近的可到达的安全城市，并且由于每个居民的移动成本是线性且独立的，因此将这些最佳的每个城市分配相加即可得出全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

MOD = 998244353

def solve():
    n, m, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, w))
        g[v].append((u, w))
    
    b = list(map(int, input().split()))
    
    last = [-1] * n
    for i, city in enumerate(b):
        last[city - 1] = i
    
    nodes = list(range(n))
    nodes.sort(key=lambda x: last[x])
    
    INF = 10**30
    dist = [INF] * n
    pq = []
    
    # activate cities in reverse safety order
    ptr = n - 1
    activated = [False] * n
    
    for i in range(n - 1, -1, -1):
        u = nodes[i]
        dist[u] = 0
        heapq.heappush(pq, (0, u))
        activated[u] = True
        
        while pq:
            d, v = heapq.heappop(pq)
            if d != dist[v]:
                continue
            for to, w in g[v]:
                if dist[to] > d + w:
                    dist[to] = d + w
                    heapq.heappush(pq, (dist[to], to))
    
    ans = 0
    for i in range(n):
        ans = (ans + (dist[i] * a[i]) % MOD) % MOD
    
    print(ans % MOD)

if __name__ == "__main__":
    solve()
```该实现构建图表并计算每个城市的最后出现索引。 然后按此索引对城市进行排序，以便那些从未受到攻击（或最早受到攻击）的城市稍后被视为更安全的目的地。 

核心机制是城市的反向激活，每个新激活的城市都作为零成本源插入到全局 Dijkstra 堆中。 松弛步骤确保每个城市最终获得到达某个安全目的地的最低成本。 

最后一个循环汇总每个城市的贡献，并按其居民人数加权。 

一个微妙的点是，该算法不会在每次激活时运行单独的最短路径计算。 相反，所有激活共享一个优先级队列，这可以保留正确性，同时避免重复重新计算。 

## 工作示例

 ### 示例 1

 输入：```
3 2 2
1 1 1
2 3 10
1 2 1
3 2
```最后攻击次数：

 城市 1 = -1，城市 2 = 1，城市 3 = 0

 按安全性排序：1（最安全）、3、2

 我们按照与此排序相反的顺序激活城市。 

| 激活城市 | 距离数组变化 | 关键放宽 |
 | ---| ---| ---|
 | 1 | 距离[1]=0 | 通过边缘 1-2 传播 |
 | 3 | 距离[3]=0 | 通过边 2-3 间接连接 |
 | 2 | 距离[2]=0 | 最终关闭|

 最终作业产量：

 城市 3 居民通过 3→2 成本 10 移动，然后 2→1 每单位传播逻辑成本 1，总共 12。 

这符合首先在城市 2 进行整合，然后迁移到城市 1 的最佳策略。 

### 示例 2

 输入：```
2 1 2
5000 5000
1 2 10000
1 2
```城市 1 和 2 都受到攻击，因此最后发生的次数都是有限的。 

激活从更安全的端点开始，但由于两者紧密相连，因此两个 dist 值通过相互激活稳定为 0。 

这表明，当所有城市都可以同时作为最终安全区时，除了初始定位之外，最优配置不需要任何移动。

 ## 边缘情况

 一个关键的边缘情况是一座城市从未受到攻击。 在这种情况下，它应该表现得永久安全。 该算法自然地处理这个问题，因为它的最后一次出现仍然是 -1，使其成为最安全的激活点之一，从而成为永久的目标源。 

另一种情况是对同一城市的多次袭击。 只有最后一次出现才重要。 例如，如果一个城市出现在第 1 天、第 5 天和第 7 天，那么只有第 7 天很重要。 预处理步骤正确地解决了这个问题。 

最后的边缘情况是在成本不对称方面的断开式结构。 尽管每个城市至少有一条道路，但有些路线可能非常昂贵，天真的贪婪分配可能会失败。 全球 Dijkstra 传播确保居民始终在整个图上找到最便宜的安全目的地，而不仅仅是本地邻近的安全城市。
