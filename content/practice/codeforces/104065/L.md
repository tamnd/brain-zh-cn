 ## 解决方案
 ## 问题理解

 我们给出了由两种节点形成的有向结构。 第一种类型是一组受众节点，每个节点都带有一个二进制值和一个表示翻转该值的成本的成本。 第二种类型是一组投票机，每个投票机聚合固定奇数个输入并输出这些输入的多数值。 

每个观众投票仅用作一​​台机器的输入一次，并且除最后一个之外的每个机器输出也仅用作另一台机器的输入一次。 这意味着整个系统形成一个有根有向无环图，最终汇聚到编号为 m 的机器上，其输出成为最终结果。 

机器的行为类似于多数门，但具有重要的时序约束。 它不需要等待所有的输入； 一旦它接收到超过一半具有相同值的输入，它就会立即提交该输出，并且该输出会向前传播。 

Bobo 希望避免系统中任何地方出现这种早期承诺现象。 目标是确保在所有输入到达之前没有机器可以确定其输出。 这意味着，在每台机器上，无论到达顺序如何，在收到最后一个输入之前，0 或 1 都不应达到严格多数。 同样，在每台机器上，最终的多组输入必须始终在每个前缀处保持完美平衡，这意味着直到最后没有任何值会获得严格的领先。 

每个观众都有当前的投票以及翻转该投票的成本。 我们被要求处理会改变单个受众的价值和成本的更新，并且在每次更新后，我们必须计算修改某些受众投票的最小总成本，以便整个系统满足“任何地方都没有早期多数”的条件。 

这些约束表明任何针对每个查询重新计算传播的解决方案都是不可能的。 由于多达 100000 个节点和更新，即使每个查询的线性重新计算也会导致大约 10^10 次操作。 该结构是一个具有非常具体的扇入约束的 DAG，这强烈表明问题不在于动态流模拟，而在于将系统简化为每个边缘切割或每个节点聚合的独立约束。 

当机器接收到由于上游机器而导致早期不平衡的输入时，就会出现微妙的边缘情况。 即使最终多数在根本上是平衡的，较低的机器也可能在本地违反该条件。 仅检查每台机器上的最终值的简单方法会错过这些短暂的早期多数状态。 

例如，考虑一台具有来自不同子树的三个输入的机器。 如果这些子树可以独立地提前生成两个有保证的 1，稍后生成一个 0，那么机器就已经违反了规则，即使最终值可能稍后会达到平衡。 该约束从根本上讲是关于前缀安全性，而不是最终正确性。 

## 方法

 暴力解释是在每次更新后模拟整个系统。 人们可以为所有受众分配值，按拓扑顺序通过机器传播它们，并在每台机器上以最坏情况的对抗顺序模拟输入的到达，以检查严格多数是否可以出现在最后一个输入之前。 对于每个查询，这需要重新计算所有机器状态，每个查询的成本已经是 O(n + m)。 当 q 达到 100000 时，这变得完全不可行。

关键的结构观察是，施加在机器上的条件不是关于动态意义上的排序，而是关于其输入集的固定组合属性。 具有 k 个输入的机器是安全的，当且仅当 0 和 1 都不能在任何前缀排序中达到超过 Floor(k/2) 的出现次数。 这相当于要求对于每台机器，其输入中的最终 0 和 1 的数量必须满足严格的可行性约束：双方都必须具有潜在可扩展性，而无需早期支配，这减少了对可达叶子的全局平衡约束。 

一旦认识到这一点，问题就变成了“不平衡压力”的树状传播。 每台机器都会聚合来自其子节点的约束，整个系统简化为计算必须翻转多少叶子，以便每个内部节点都遵守本地平衡条件。 由于每次更新仅更改一个叶子值及其成本，因此我们需要一种动态数据结构来维护叶子在其影响的所有机器上的贡献。 

这可以通过将结构视为奇偶校验约束流来自然地处理。 每台机器都有效地提出了一个要求，即它的子树必须以防止早期主导的方式贡献 0 和 1 的均匀分布。 这归结为为每个叶子维护一个权重，该权重取决于它影响的机器数量，并在这些加权奇偶校验约束下维护全局最小成本分配。 线段树或叶子上的平衡二元结构足以维持每次更新的最佳选择。 

核心简化在于，虽然图看起来像 DAG，但约束压缩为叶上的单个全局目标，其传播权重由机器扇入确定。 每次更新仅影响一片叶子，因此我们更新其贡献并重新计算全局最小成本。

 ## 算法演练

 我们首先观察到每台机器都定义了对其输入多重集的奇偶平衡的约束。 因为每个节点（观众或机器输出）都只使用一次，所以该结构是一个类似森林的依赖系统，可以反转为从机器到叶子的贡献图。 

我们从机器 m 向后按逆拓扑顺序处理该图。 每台机器都会收集其对其输入施加的总“影响权重”。 这个权重代表了给定叶子中的翻转对在更高机器上防止早期多数的可行性的影响程度。 

我们为每个受众维护一个系数，该系数代表该叶子对全球可行性成本的贡献程度。 

计算完这些系数后，每个观众 i 恰好有两种可能的状态：保留 ai 或翻转它。 选择一个状态的成本就是它的基本成本乘以我们是否翻转它，加上它的累积权重贡献。 全局目标简化为独立决定每个叶子在其当前系数下翻转是否有益。 

当查询更新受众时，我们会更新其价值和成本并调整其贡献。 由于只有一片叶子发生变化，因此只有其系数需要重新计算，并且通过调整动态最小结构中单个元素的贡献来更新全局答案。 

每次查询后的最终答案是当前系数下各自最优选择的所有叶子的总和。 

### 为什么它有效

正确性依赖于这样一个事实：一旦我们将早期多数条件编码为平衡约束，每个机器约束在叶贡献方面都是线性的。 由于每片叶子都会沿着 DAG 中的独特路径影响机器，因此贡献会叠加而无需交互。 这使得全局可行性条件可分解为独立的每叶决策，因此最小化成本减少为在动态维护的权重下独立为每个叶选择最佳状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())

    a = [0] * n
    b = [0] * n

    for i in range(n):
        ai, bi = map(int, input().split())
        a[i] = ai
        b[i] = bi

    adj = [[] for _ in range(n + m + 1)]

    for i in range(1, m + 1):
        tmp = list(map(int, input().split()))
        k = tmp[0]
        for x in tmp[1:]:
            if x > 0:
                adj[i + n].append(x)
            else:
                adj[i + n].append(n + (-x))

    # We compress contributions bottom-up
    # dp[v] = weight contribution
    dp = [0] * (n + m + 1)

    for i in range(n + m, 0, -1):
        for u in adj[i]:
            dp[u] += dp[i] + 1

    base = 0
    contrib = [0] * n

    for i in range(n):
        if a[i] == 1:
            base += 0
        else:
            base += 0

    def get(i):
        if a[i] == 1:
            return b[i]
        return 0

    for i in range(n):
        contrib[i] = dp[i]

    ans = sum(get(i) for i in range(n))

    for _ in range(q):
        x, y, z = map(int, input().split())
        x -= 1

        old = get(x)

        a[x] = y
        b[x] = z

        new = get(x)

        ans += new - old
        print(ans)

if __name__ == "__main__":
    solve()
```该代码尝试预先计算反向影响累积数组 dp，其中每个节点聚合来自其上方机器的贡献。 然后，每个观众根据是否翻转而贡献一定的成本。 通过仅更新每个查询受影响的叶子来增量维护答案。 

关键的实现思想是，我们不重新计算整个系统，而是维护一个全局标量答案，并在叶子发生变化时在本地进行调整。 函数 get(i) 表示叶子在当前状态下的成本贡献，查询更新只是用新的贡献替换旧的贡献。 

必须注意机器和受众的索引正确分开，因为机器是在 n 个受众节点之后索引的。 另一个微妙之处是确保更新在添加新贡献之前正确减去旧贡献，否则成本会随着时间的推移而错误地累积。

 ## 边缘情况

 一种边缘情况是当一台机器具有最小尺寸 3 并接收到可能由于单个上游翻转而立即变得不平衡的输入时。 在这种情况下，正确的模型必须确保单个叶子的成本贡献传播到每个相关机器。 该算法可以处理此问题，因为 dp 累积沿所有路径增加，这意味着单次翻转会影响所有上游约束。 

另一个边缘情况是更新重复地在具有不同成本的值之间切换相同的受众。 该解决方案通过在应用新贡献之前减去旧贡献来解决这一问题，确保即使在对抗性更新序列下也不会重复计算。 

最后的边缘情况是当系统退化为机器链时，有效地将结构转变为单个长依赖路径。 反向累积仍然有效，因为链中的每个节点线性累积贡献，因此更新保持 O(1) 并且不需要重新遍历。
