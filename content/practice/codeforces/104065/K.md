 ## 解决方案
 ## 问题理解

 我们有两个字符串：一个模式字符串`s`和一个文本字符串`t`。 任务是计算有多少个起始位置`t`产生发生`s`作为连续的子字符串。 允许重叠，因此每个有效的匹配都会独立地贡献答案。 

查看此内容的一个直接方法是我们滑动`s`跨越每一个可能的对齐方式`t`并检查所有字符是否匹配。 输出是完全匹配的比对总数。 

限制是极端的：两个字符串的长度可以是$10^7$。 这排除了任何以嵌套方式重复比较字符的解决方案。 即使每次对齐进行线性扫描也意味着最多$10^{14}$在最坏的情况下进行字符比较，这是远远不可行的。 

内存在精神上也是紧张的，尽管名义上的限制很大。 关于顺序访问和“低空间”框架的注释表明，我们应该避免存储大型辅助结构，例如用于非常大的串联或需要随机访问模式的多遍预处理的完整前缀函数表。 

微妙的边缘情况来自于高度重复的字符串。 如果`s = "aaaaa"`和`t = "aaaaaaaaaa"`，每个对齐方式都以重叠方式有效。 幼稚的不匹配提前退出策略仍可能退化为二次行为，因为不匹配很少见并且比较会反复重新启动。 

另一个边缘情况是当`s`长度为 1。然后中的每个字符`t`是一个独立的匹配检查，答案只是该字符的频率。 这通常会在滑动实现中暴露出相差一的错误。 

## 方法

 蛮力的想法很简单。 对于每个职位`i`在`t`从`0`到`m - n`，我们比较`s`与子字符串`t[i:i+n]`逐个字符。 如果所有字符都匹配，我们将增加答案。 

这是正确的，因为它直接强制子字符串相等的定义。 故障模式是性能。 每次对齐可能需要最多`n`进行比较，并且有`m - n + 1`对齐，给出最坏情况的复杂性$O(nm)$。 两者都达到$10^7$，这变得完全不可行。 

关键的观察是我们不需要在每次转变时从头开始重新比较字符。 模式中重复前缀信息的结构允许我们重用部分匹配。 当发生不匹配时，我们想知道在不从零重新开始的情况下，我们可以在模式中“回退”多远。 

这正是 Knuth-Morris-Pratt 算法中的前缀函数所捕获的内容。 它编码最长的正确前缀`s`这也是每个前缀的后缀`s`。 有了这些信息，我们就可以扫描`t`一次并保持多少个字符`s`我们目前已匹配。 中的每个角色`t`最多导致恒定数量的指针调整`s`。 

内存问题得到解决，因为前缀数组的大小`n`，这是可以接受的，并且扫描是纯粹顺序的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nm)$|$O(1)$| 太慢了 |
 | KMP |$O(n + m)$|$O(n)$| 已接受 |

 ## 算法演练

 我们使用 KMP 来计算单次文本中模式出现的次数。 

### 步骤

 1. 计算前缀函数`pi`对于字符串`s`。 

对于每个位置`i`,`pi[i]`存储最长的正确前缀`s[:i+1]`这也是该子字符串的后缀。 这个结构告诉我们在不匹配之后我们可以继续匹配多远而无需从零重新开始。 
2. 初始化一个指针`j = 0`，代表有多少个字符`s`目前正在匹配`t`。 
3.扫描文字`t`使用索引从左到右`i`。 对于每个角色`t[i]`，尝试延长当前匹配。 
4.如果`t[i] != s[j]`，反复回退使用`j = pi[j-1]`直到`j == 0`或者找到匹配项。 

这确保我们始终保留最长的有效部分匹配，而不是从头开始。 
5. 如果`t[i] == s[j]`, 增量`j`加 1，扩展匹配的前缀。 
6.如果`j == n`, 完整匹配`s`结束于位置`i`。 增加答案并重置`j = pi[j-1]`允许重叠匹配。 

### 为什么它有效

 在每一个位置上`t`，变量`j`表示最长前缀的长度`s`与已处理前缀的后缀匹配`t`。 前缀函数保证在不匹配之后，任何仍然可以匹配的较短前缀已经被编码在`pi`，所以我们永远不会错过有效的对齐。 每场完整比赛此时都会被检测到一次`j`达到`n`，保证正确无重复、无遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_pi(s):
    n = len(s)
    pi = [0] * n
    j = 0
    for i in range(1, n):
        while j > 0 and s[i] != s[j]:
            j = pi[j - 1]
        if s[i] == s[j]:
            j += 1
        pi[i] = j
    return pi

def solve():
    n, m = map(int, input().split())
    s = input().strip()
    t = input().strip()

    pi = build_pi(s)

    j = 0
    ans = 0

    for ch in t:
        while j > 0 and ch != s[j]:
            j = pi[j - 1]
        if ch == s[j]:
            j += 1
        if j == n:
            ans += 1
            j = pi[j - 1]

    print(ans)

if __name__ == "__main__":
    solve()
```该实现自然地分为前缀函数构造和流匹配阶段。 前缀数组构建一次`s`，然后在扫描期间重复使用`t`。 

主扫描只维护两个变量，当前索引在`s`和答案计数器。 回退循环至关重要：它确保不匹配不会导致我们不必要地重新启动。 

一个常见的陷阱是忘记重置`j`找到匹配后。 没有`j = pi[j - 1]`，重叠的匹配会丢失。 另一个问题是索引：`s[j]`仅在以下情况下有效`j < n`，因此在越界访问之前必须进行相等性检查，这是通过检查来保证的`j == n`增量后立即。

 ## 边缘情况

 一种重要的边缘情况是模式具有严重的自我重叠。 例如，`s = "aaaa"`和`t = "aaaaaaaa"`。 在扫描过程中，`j`反复达到4并重置为`pi[3] = 3`，允许立即继续。 这确保了每个有效的对齐都被计算在内，包括那些几乎完全重叠的对齐。 

另一种情况是完全不匹配的文本，例如`s = "abc"`和`t = "zzz..."`。 这里`j`反复保持为零，并且算法仅执行简单比较而不进入后备循环，这证明了 KMP 的摊余常数行为。 

第三种情况是单字符模式。 该算法完全退化为在没有任何前缀结构的情况下对出现次数进行计数，因为`j`总是 0 或 1 并且`pi`是微不足道的。
