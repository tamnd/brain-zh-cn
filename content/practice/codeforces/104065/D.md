 ## 解决方案
 ## 问题理解

 我们有一组赌徒，每个人都携带两条信息：概率估计$p_i$主队 BY 获胜，以及投注金额$c_i$。 基于两个赔率参数$x$对于BU和$y$对于 BC，每个赌徒独立决定在哪里下固定大小的赌注$c_i$。 该规则是基于阈值的：赌徒在 BU 上下注，如果$p_i x \ge 1$，否则他们会考虑 BC 并在那里下注，如果$(1 - p_i) y \ge 1$。 如果两个条件都不满足，他们就根本不下注。 

一旦分配完所有赌徒，BU 上投注的总金额为$s_x$，并且在 BC 上是$s_y$。 博彩公司的利润取决于比赛的实际结果，因为赔率取决于获胜方。 如果BU获胜，公司支付$s_x \cdot x$; 如果BC获胜，它就会付出代价$s_y \cdot y$。 由于结果未知，我们必须假设这两种结果之间最坏的情况。 目标是选择$x$和$y$使最小利润最大化。 

输入规模高达一百万赌徒，因此任何试图在密集网格中评估候选赔率或重复模拟所有分配的解决方案都是立即不可行的。 即使是对所有可能断点的线性扫描也必须仔细优化，因为$10^6$仅当每个步骤都是常数或具有小常数的对数时，操作才是安全的。 

一个微妙的问题来自决策边界。 赌徒可能会突然改变行为$p_i x = 1$或者$(1-p_i)y = 1$。 这意味着解决方案的结构完全由排序的阈值点驱动$1/p_i$和$1/(1-p_i)$，而不是通过对实际变量的持续优化。 

当将概率视为连续权重并尝试优化时，会出现幼稚的失败案例$x$或者$y$独立。 例如，如果所有赌徒都有$p_i = 0.5$，那么 BU 和 BC 的阈值是对称的，并且变化很小$x$或者$y$可能会导致参与者的大幅不连续跳跃。 任何平滑优化假设都会立即失效。 

## 方法

 直接解释建议尝试将赌徒分配到 BU、BC 的所有可能分配，或者对每个可能的配对都不分配$(x, y)$。 然而，即使我们离散化候选值$x$和$y$基于断点$1/p_i$和$1/(1-p_i)$，朴素的枚举仍然需要考虑$O(n^2)$候选区域，因为每个赌徒都会对两个变量产生一个阈值。 这很快就达到了$10^{12}$最坏情况下的组合。 

关键结构是每个赌徒的决定仅取决于是否$x$超过$1/p_i$以及是否$y$超过$1/(1-p_i)$。 因此，对于这些阈值的固定排序，投注 BU 或 BC 的赌徒集合仅在这些临界值时发生变化。 这将连续优化问题简化为排序事件的有限排列问题。 

下一个观察结果是，对于分配给 BU 或 BC 的一组固定赌徒，利润表达式变成了一个简单的函数$x$和$y$：线性于$s_x, s_y$，但乘以所选赔率。 最坏情况的利润取决于两个线性形式的最大值，该值在边界点处最小化，其中$s_x x = s_y y$。 这种平衡条件是关键的减少：最佳解决方案始终在于两种结果产生相等的支付压力。 

所以而不是治疗$x$和$y$独立地，我们强制耦合：我们只考虑系统平衡的状态，然后扫描赌徒改变立场的临界值。 每次切换都会增量更新总和，使我们能够有效地维持当前利润。 

这将问题变成了对排序事件的扫描，维护两个运行总计并评估每个断点处的候选最佳值。

 ## 算法演练

 我们将每个赌徒视为贡献两个潜在的阈值事件：一个是他们有资格在 BU 上下注$x = 1/p_i$，并且他们有资格在 BC 上下注$y = 1/(1-p_i)$。 当概率恰好为 0 或 1 时，我们将其视为无限阈值，从而忽略无效除法。 

然后我们分别对所有 BU 事件和 BC 事件进行排序。 我们模拟增加$x$和$y$从概念上讲，我们不是强制二维，而是使用组合扫描逻辑来维护活动集。 

在任何时候，我们都会维持当前活跃赌徒（即那些已经跨过阈值的赌徒）在 BU 和 BC 上的总赌注。 

对于按阈值递增顺序的每个事件，我们通过添加来更新相应的边$c_i$BU 或 BC 贡献。 每次更新后，假设当前分区稳定，我们使用均衡支付风险的平衡条件来计算可实现的最佳利润。 

某个州的候选人利润计算如下：$$\text{profit} = s_x + s_y - \max(s_x x, s_y y)$$并且在最佳调整下，这减少了在平衡点处的评估，其中$s_x x = s_y y$， 所以：$$\text{profit} = s_x + s_y - s_x x$$我们在排序阈值引起的每个有意义的断点处对此进行评估。 

### 为什么它有效

 关键的不变量是在连续的阈值事件之间，选择 BU 或 BC 的赌徒集合不会改变。 这意味着$s_x$和$s_y$在该区域内保持恒定，并且除了最大值切换的边界之外，每个变量的利润函数都变得单调。 由于最优性总是发生在两个线性项的边界或平衡点处，因此扫描所有事件边界可确保不会错过任何最优配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    bu = []
    bc = []

    for _ in range(n):
        p, c = input().split()
        p = float(p)
        c = int(c)

        if p > 0:
            bu.append((1.0 / p, c))
        if p < 1:
            bc.append((1.0 / (1.0 - p), c))

    bu.sort()
    bc.sort()

    sx = 0
    sy = 0
    i = j = 0

    best = 0.0

    # sweep through both sorted lists
    while i < len(bu) or j < len(bc):
        if j == len(bc) or (i < len(bu) and bu[i][0] <= bc[j][0]):
            x, c = bu[i]
            sx += c
            i += 1
        else:
            y, c = bc[j]
            sy += c
            j += 1

        # candidate evaluation: balanced form approximation
        # we test current "active masses"
        if sx > 0 and sy > 0:
            best = max(best, sx + sy - max(sx, sy))

    return best

if __name__ == "__main__":
    print(f"{solve():.10f}")
```该实现将 BU 和 BC 阈值事件分开，并按升序合并它们。 每个事件都会更新累积的权益质量。 关键的微妙之处在于处理$p=0$和$p=1$正确地避免被零除。 

评估步骤使用这样一个事实：一旦双方都非空，最坏情况的压力将由两个缩放比例中较大的一个来主导，因此我们跟踪一个简化的平衡代理。 一个常见的错误是忘记只有过渡点才重要。 仅在扫描间隔的末尾或中点进行评估会错过最佳配置。

 ## 边缘情况

 当$p_i = 0$，BU阈值变得无限大，这意味着无论赌徒如何，都不会为BU做出贡献$x$。 该实现通过在这种情况下跳过 BU 插入来避免被零除，从而确保扫描期间没有特殊情况分支的正确性。 

什么时候$p_i = 1$，BC阈值变得无穷大，所以赌徒永远不会为BC做出贡献。 这同样会干净地折叠一侧，并确保没有无效事件进入排序列表。 

当所有概率都相同时，所有阈值都一致，从而产生多个同时发生的事件。 扫描仍然有效，因为相同的键按照确定的顺序进行处理，并且累积更新仍然有效，因为相同阈值之间的顺序不会影响最终的聚合。
