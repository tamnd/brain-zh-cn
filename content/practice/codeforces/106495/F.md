 ## 解决方案
 ## 问题理解

 我们得到一个正整数列表和一个初始值`x`。 我们可以选择列表的任何顺序。 选择顺序后，我们将数字一一处理。 每个处理过的数字都会用除以该数字时的余数替换当前值。 目标是排列数字，使最终值尽可能大。 

输入由数组长度、数组值和起始值组成。 输出是所有模运算完成后可以保留的最大值。 顺序很重要，因为模运算可能会破坏后续运算无法恢复的信息。 

数组长度很小，最多 21，但值本身可能非常大。 这排除了尝试所有排列，因为`21!`远远超出了可以运行的范围。 解决方案必须利用少量元素而不是数字大小。 状态空间为`2^21`大约有 200 万个状态，这在低级语言中是可行的，并且在小心使用内存的情况下在 Python 中仍然可以管理。 

一个常见的错误是假设应首先或最后应用较大的除数。 例如，与`x = 15`和数字`[5, 6, 7]`，将最大除数放在第一位给出`15 % 7 = 1`， 然后`1 % 5 = 1`， 然后`1 % 6 = 1`。 最优顺序是`5, 7, 6`，生产`15 % 5 = 0`,`0 % 7 = 0`,`0 % 6 = 0`，这仍然不是最佳的。 实际答案是通过以下方式获得的`7, 6, 5`:`15 % 7 = 1`,`1 % 6 = 1`,`1 % 5 = 1`。 此示例表明，仅基于除数大小的贪婪选择无法捕获操作之间的依赖关系。 

另一种边缘情况是某些值已经很小。 如果当前值小于每个剩余除数，则所有未来的模运算将保持其不变。 例如，输入：```
2
10 20
5
```答案是`5`。 不考虑当前状态而继续应用转换的粗心实现可能会错误地期望该值会减小。 

重复的值也需要小心。 为了：```
3
5 5 100
12
```答案是`2`。 两个相同的除数是单独的运算，因此必须考虑两者。 将值视为集合而不是索引元素会丢失有效顺序。 

## 方法

 直接的方法是尝试所有可能的排序。 对于每个排列，模拟模运算并保留最大的最终值。 这是正确的，因为每种可能的排列都会被检查。 然而，排列的数量是`n!`，并且对于`n = 21`这是关于`5.1 * 10^19`的可能性。 即使每秒十亿次操作也无法使这种方法变得实用。 

关键的观察是许多不同的订单达到相同的中间情况。 使用某些数字后，唯一重要的是哪些数字仍然可用以及当前值是多少。 由于当前值始终是通过模运算从初始值生成的，因此我们可以存储在处理特定索引子集后可达到的最佳值。 

对于已使用元素的每个子集，我们接下来尝试添加每个未使用的元素。 这种转换只是再应用一次模运算。 有`2^n`子集，每个子​​集最多检查`n`下一个选择，给出关于`n * 2^n`运营。 

重要的减少是我们从不关心产生子集的确切顺序。 如果两个不同的阶使用同一组元素，则只有较大的当前值才重要，因为未来的模运算相对于当前值是单调的。 在应用相同的剩余操作后，较小的当前值永远不会变得比较大的当前值更好。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n! * n) | O(n! * n) | O(n) | 太慢了|
 | 最佳| O(n * 2^n) | O(n * 2^n) | O(2^n) | O(2^n) | 已接受 |

 ## 算法演练

 1. 创建数组`dp`在哪里`dp[mask]`表示精确使用索引设置的元素后可达到的最大电流值`mask`。 空掩码以原始值开始`x`因为还没有发生任何操作。 
2. 迭代所有掩码。 对于每个可达状态，尝试掩码中未包含的每个元素。 这表示选择排列中的下一个数字。 
3. 对所选元素应用模运算。 更新包含旧掩码加上新元素的状态，其中新元素的当前内容和新获得的值之间的最大值。 
4. 处理完所有子集后，完整掩码包含答案，因为每个数组元素都已被恰好使用一次。 

为什么它有效：不变的是`dp[mask]`始终在精确使用中的元素后存储最佳可能值`mask`。 转换会尝试所有可能的下一个选择，因此会探索每个部分排序的每个可能的延续。 仅保留子集的最大值是安全的，因为当应用相同的除数时，未来的模运算无法使较小的起始值击败较大的起始值。 

## Python 解决方案```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    x = int(input())

    size = 1 << n
    dp = array('Q', [0]) * size
    dp[0] = x

    for mask in range(size):
        cur = dp[mask]
        if cur == 0 and mask != 0:
            continue
        remaining = ((1 << n) - 1) ^ mask
        while remaining:
            bit = remaining & -remaining
            i = bit.bit_length() - 1
            nxt = mask | bit
            val = cur % a[i]
            if val > dp[nxt]:
                dp[nxt] = val
            remaining -= bit

    print(dp[-1])

if __name__ == "__main__":
    solve()
```这`dp`数组使用`array('Q')`而不是普通的 Python 列表。 有超过两百万个状态，因此存储 Python 整数对象会浪费大量内存。 每个存储的值都适合无符号 64 位整数，因为所有输入最多`10^18`。 

转换循环使用以下方法从剩余元素中提取一组位`remaining & -remaining`。 这避免了扫描不必要的操作，也避免了创建额外的列表。 索引恢复为`bit_length() - 1`。 

支票为`cur == 0`跳过无用的状态。 一旦当前值变为零，以后的每个模运算都会使其保持为零，因此该状态的所有后代也将为零。 最终状态是`dp[(1 << n) - 1]`，这与`dp[-1]`因为完整掩码是最后一个索引。

import sys
import io
from array import array

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    x = int(input())

    size = 1 << n
    dp = array('Q', [0]) * size
    dp[0] = x

    for mask in range(size):
        cur = dp[mask]
        if cur == 0 and mask:
            continue
        rem = (size - 1) ^ mask

            i = bit.bit_length() - 1
            nxt = mask | bit
            val = cur % a[i]
            if val > dp[nxt]:
                dp[nxt] = val
            rem -= bit

    return str(dp[-1])

 ## 边缘情况

 对于起始值已经小于每个除数的情况：```
2
10 20
5
```初始状态有价值`5`。 两种可能的下一个选择都会产生`5 % 10 = 5`或者`5 % 20 = 5`。 以后的每次操作都会保持该值不变，因此全掩码状态保持不变`5`。 

对于重复元素：```
3
5 5 100
12
```DP 不会合并两个五，因为状态是基于指数的。 一条路径使用第一个路径`5`，另一个使用第二个`5`，并且这两个操作仍然独立可用。 最好的路径是`100, 5, 5`, 给予`12 % 100 = 12`， 然后`12 % 5 = 2`， 然后`2 % 5 = 2`。 

对于到达零的路径：```
4
2 4 8 16
1000000000000000000
```DP可能会遇到应用除数后当前值变为零的状态`2`。 从该状态开始的所有转换都保持为零，这就是为什么跳过这些状态是正确的。 最终答案仍然是零。
