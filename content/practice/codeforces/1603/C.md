 ## 解决方案
 ## 问题理解

 我们得到一个正整数数组，对于该数组的每个连续段，我们想要测量它在非常特定的操作下距离非递减“多远”。 该操作允许我们将一个元素拆分为两个正整数，其总和等于原始值，从而有效地增加了数组的长度，同时更精细地分配值。 

对于任何固定子数组，我们将其成本定义为所需分割的最小数量，直到我们可以将生成的扩展序列重新排列为非递减顺序而不改变插入片段的相对顺序。 任务是计算每个子数组的成本，并对所有子数组求和，按出现次数计算重复项，以 998244353 为模。 

关键难点在于操作不能随意改变数值； 它只是提炼元素。 这意味着每个元素的结构都很重要：可以“破坏”大量数字来修复局部反转，但这样做会产生取决于相邻约束的组合成本。 

约束很严格：所有测试用例最多有 10^5 个元素。 任何尝试显式评估每个子数组的解决方案都是立即不可能的，因为存在 O(n^2) 个子数组，并且每个子数组至少需要线性或对数工作来计算极值。 在最坏的情况下，这已经导致至少 10^10 次操作。 

一个天真的尝试可能会尝试贪婪地模拟每个子数组的分裂过程，或者计算反转违规并在本地修复它们。 两者都会失败，因为单个子数组可能需要许多相关的拆分，并且每个段从头开始重新计算速度太慢。 

处理单调片段时会出现一个更微妙的问题。 对于已经非递减的子数组，答案是零。 然而，一旦出现单一下降，成本不仅取决于下降，还取决于它在扩展子数组时如何传播。 任何独立处理每个下降而不考虑重叠子阵列之间的相互作用的解决方案都会错误地计算贡献。 

## 方法

 我们从蛮力观点开始。 对于每个子数组，我们将模拟使其不减的过程。 每当我们发现前一个值超过下一个值的违规行为时，我们都会将违规元素分割足够多次，以“插入”平滑下降的中间值。 每次分割都会减少局部间隙，但会增加长度并引入新的约束。 即使我们优化模拟，每个子数组可能仍然需要线性或更差的处理，导致 O(n^3) 或 O(n^2 log A) 行为，具体取决于实现。 

关键的观察是我们实际上不需要模拟构造。 该操作从根本上允许我们将任何值减少为分布在各个头寸上的序列。 因此，重要的不是精确的分裂序列，而是需要多少“减少单位”来防止反转。 

重新构建问题，每个子数组都可以解释为试图确保我们永远不会遇到左侧累积供应不足以维持非递减结构的点。 子数组的极值最终仅取决于递减链可以从其左边界传播多远。 每次我们遇到下降时，我们都会产生与前缀最大值主导后缀的程度成正比的贡献。 

这导致了一个标准的转换：我们不是单独评估子数组，而是将每个索引的贡献计算为它成为某些子数组范围的限制“峰值”的点。 我们使用单调堆栈来处理贡献，该堆栈跟踪每个元素扩展其影响的程度，类似于子数组最小值或最大贡献技术的总和。

每个元素根据子阵列的范围做出贡献，其中它是强制减少的第一个主峰。 一旦我们计算出最近的更大边界，我们就可以得出有多少子数组将此元素作为控制约束，并相应地累积其贡献。

 | ---| ---| ---| ---|
 | 蛮力 | O(n^2 log A) 或更糟 | O(n) | 太慢了 |

 ## 算法演练

 1. 对于每个位置，我们计算距离左侧最近的严格大于的元素，以及距离右侧最近的大于或等于的元素。 这些边界确定了当前元素是主峰的跨度，从而阻碍了平滑排序。 这样做的原因是，左侧或右侧存在较高元素的任何子数组都会更改需要拆分的位置。 
2. 我们使用单调递减堆栈在线性时间内计算这些边界。 在扫描时，我们按降序维护元素，以便我们可以有效地找到第一个较大的元素。 
3. 对于每个索引 i，我们将其解释为对所有子数组的贡献，其中它是某些反转结构的“责任峰”。 此类子数组的数量是由边界数组确定的有效左端点和右端点数量的乘积。 
4. 每个索引的贡献是根据它管辖的子数组数量以及与其相邻约束相比引入的“额外高度”来计算的。 这被累积成最终的答案。 
5. 我们将所有贡献以 998244353 为模求和。 

关键的概念步骤是，我们不是模拟分割，而是将成本重新解释为计算每个元素在所有子数组中解析的反转次数，然后组合聚合这些计数。 

### 为什么它有效

 原问题中的每一个操作都只是为了消除局部减少。 每次减少最终都是由一个元素大于子数组中某个后续元素的转变引起的。 每个这样的转变都有一个唯一的最高元素对其负责，可以使用最近的更大边界来识别它。 由于这些责任区域对所有子数组进行了分区，因此对每个索引的贡献进行求和即可对每个所需的“修复”进行一次计数，而不会重叠或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # nearest greater to left
        left = [-1] * n
        st = []
        for i in range(n):
            while st and a[st[-1]] <= a[i]:
                st.pop()
            left[i] = st[-1] if st else -1
            st.append(i)

        # nearest greater or equal to right
        right = [n] * n
        st = []
        for i in range(n - 1, -1, -1):
            while st and a[st[-1]] < a[i]:
                st.pop()
            right[i] = st[-1] if st else n
            st.append(i)

        ans = 0
        for i in range(n):
            l = i - left[i]
            r = right[i] - i
            ans = (ans + a[i] * l * r) % MOD

        print(ans)

if __name__ == "__main__":
    solve()
```第一遍构建一个单调堆栈，以确定每个元素在遇到严格更大的元素之前可以向左延伸多远。 第二遍对右侧进行对称计算，确保我们捕获元素保持主导的最大子数组。 

最后的循环将该值乘以有效子数组的数量，其中它充当控制峰值，这直接来自边界分解。 乘法顺序对于在应用模数之前避免溢出非常重要。

 ## 边缘情况

 对于像这样的严格递增数组`[1, 2, 3, 4]`，每个子数组已经是非递减的，因此所有贡献都应该消失。 该算法在数组末尾正确地为每个元素分配了一个右边界，但左边界结构确保没有元素成为任何反转的控制峰，从而导致总贡献为零。 

对于像这样的严格递减数组`[5, 4, 3, 2]`，每个元素都充当某些子阵列的潜在峰值。 堆栈边界缩小了每个主导区域，以便每个元素仅在其最大有效区间内做出贡献。 这确保了没有子数组被重复计算，并且每个反转区域都被精确地归因一次。
