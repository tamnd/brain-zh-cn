 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，目标是使用非常特殊的操作完全擦除它。 在每一步中，我们都可以选择一个其值**不可被其基于 1 的索引加一整除的元素，并将其删除。 删除后，序列缩小，剩余元素的索引左移一位。 挑战在于确定是否存在最终清空序列的移除顺序。 

输入提供多个测试用例，每个测试用例都有序列的长度和序列本身。 如果可以完全去除，则输出为“YES”，否则输出为“NO”。 

约束很大：序列可以达到大小$10^5$，所有测试用例上的所有序列的总和可以达到$3 \cdot 10^5$。 一个简单的模拟，一个一个地删除元素并在每一步检查可分性，将大致具有最坏情况的复杂性$O(n^2)$，这太慢了。 这意味着我们需要一个序列长度呈线性或接近线性的解决方案。 

当元素很小且索引增长时会出现边缘情况。 例如，如果单个元素 2 位于索引 1 处，则无法删除它，因为$2 \% 2 = 0$。 另一个微妙的情况是具有重复数字的序列：元素的可移除性取决于其**当前位置**，而不是其原始位置。 

## 方法

 暴力方法会尝试所有删除序列。 在每一步中，扫描数组，选择任意元素$a_i$这样$a_i \% (i+1) \neq 0$，并将其删除。 继续，直到序列为空或没有可移除的元素。 这在原则上是正确的，但对于$n = 10^5$, 扫描最多$n$元素为$n$步骤给出$O(n^2)$，这太慢了。 

关键的见解是**向后工作**。 如果我们从最后一步开始对位置进行编号，当只剩下一个元素时，该元素必须满足其在收缩序列中的位置的整除条件。 我们可以反向模拟删除：从最后一个元素开始（位置$n$在原始数组中），检查是否$a_i$可被简化序列中的**最终基于 1 的位置**整除。 如果是，则无法移除； 如果没有，可以将其删除。 通过从末尾迭代到开头，我们只需要对数组进行一次遍历。 

这种方法利用了这样的观察结果：在每个阶段，“最难”删除的元素位于当前数组的末尾。 如果该元素从其收缩位置开始计算时是可移除的，那么也可以处理所有较早的元素。 这将复杂性降低到$O(n)$每个测试用例。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n²) | O(n) | 太慢了 |
 | 反向检查（最佳）| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量$t$。 
2. 对于每个测试用例，请阅读$n$和顺序$a$。 
3. 初始化计数器$current\_length = n$。 这表示用于检查整除性的“距末尾的位置”。 
4. 从最后一个元素到第一个元素向后迭代数组。 对于每个元素$a[i]$:

 a. 如果$a[i] \% current\_length == 0$，打印“NO”并停止检查此测试用例。 

b. 否则，递减$current\_length$减一并继续。 
5. 如果循环结束时没有遇到可整除的元素，则打印“YES”。 

**为什么有效**：在每一步中，收缩序列中的最后一个元素必须根据其**当前基于 1 的索引**可移除。 通过反向检查元素，我们保证每个元素在成为最后一个候选元素时满足可分性要求。 如果任何元素失败，则没有任何删除序列可以将其删除，因此答案是“否”。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    possible = True
    current_length = n
    for value in reversed(a):
        if value % current_length == 0:
            possible = False
            break
        current_length -= 1
    print("YES" if possible else "NO")
```该解决方案使用有效地读取输入`sys.stdin.readline`。 我们反向迭代该序列，因为元素的可分性取决于其考虑删除时的最终位置。 这`current_length`变量跟踪这个虚拟位置。 如果任何元素可以被其位置整除，则操作无法成功，因此我们将测试用例标记为不可能。 否则，我们递减计数器并继续。 最终的打印语句以预期的格式输出答案。

 ## 边缘情况

 无法删除只有一个元素等于其从 1 开始的索引加 1 的序列。 例如，`[2]`失败是因为$2 \% 1 = 0$。 该算法在反向循环的第一次迭代中正确识别了这一点并输出“NO”。 

对于所有元素都等于 1 的序列，反向检查见`1 % n`,`1 % (n-1)`等，除了`1 % 1`，这是允许的。 解决方案输出“YES”。 

对于数字较大的序列，可整除性检查以模为基础进行`current_length`，永远不会超过$10^5$，因此不会发生整数溢出。
