 ## 解决方案
 ## 问题理解

 我们正在尝试确定一个未知的整数参数$W$，文本编辑器中行的宽度。 我们提交的每篇文章都是表示字长的正整数序列。 编辑器将文章格式化为行，将单词按顺序排列在一行上，直到添加的单词超过$W$，然后换行到新行。 如果任何一个词超过$W$，文章根本无法显示。 如果无法显示文章，编辑器会告诉我们所使用的行数或零。 每个测试用例最多允许两个查询来确定$W$。 

约束允许最多$10^5$每个查询的字数和$W \le 10^5$，因此任何算法都必须在每个查询的线性时间内运行。 关键边缘情况涉及非常小或非常大$W$相对于我们提交的文字。 例如，提交一个等于未知数的单词$W$总是会成功，同时提交的单词长于$W$立即失败。 天真地查询许多单词长度的组合将超出查询限制。 

例如，粗心的实现可能会将字长相加并除以要猜测的行数$W$。 当换行符与除以行的总和不完全对齐时，此操作会失败。 一个具体的例子：如果$W=20$我们提交`[1,9,4,6,1]`，编辑器生成 2 行，但简单地将 21（总长度）除以 2 得到 10.5，这不是$W$。 正确的推理必须尊重换行是如何发生的。 

## 方法

 蛮力方法是提交增加字长的文章，根据返回的行数进行调整，直到我们隔离$W$。 这在原则上是正确的，因为观察序列占用多少行会限制$W$。 但是，它可能需要很多查询，超出了允许的两个查询。 它还需要仔细选择单词序列以避免早期失败。 

关键的观察是我们可以构建查询来精确定位$W$完全分两步。 第一个查询可以设计为饱和一行，如果满足以下条件，则生成多行响应：$W$小于总长度。 第二个查询可以尝试将所有单词放在一行上，总长度等于候选单词$W$。 如果编辑报告成功，我们就知道$W$至少是这个总数； 如果失败的话$W$较少。 通过两个精心构造的查询，我们可以确定$W$恰恰。 

最佳方法之所以有效，是因为编辑器的换行规则是确定性的。 通过提交一个单词序列，其中所有单词的大小相同或者总长度受到控制，我们可以对返回的行数进行编码$W$。 例如，一根线的长度超过$W$保证失败，而几乎填满一行的序列允许我们计算$W$从响应中。

 ## 算法演练

 1.读取测试用例数量$t$。 对于每个测试用例，我们需要确定$W$独立。 
2. 对于每个测试用例，使用涵盖较大总长度的单词序列构建查询，例如，一个小单词后面跟着一个非常大的单词，使得它们的总和超出最大可能值$W$。 这确保编辑器可以换行或拒绝文章，提供有关上限的信息$W$。 
3.提交第一个查询并读取返回的行数，$l_1$。 如果编辑器返回零，则查询中最大的单词超过$W$。 在这种情况下，$W$小于该单词的长度，因此我们立即知道候选最大值$W$。 
4. 构造第二个查询，使单词的总长度等于候选单词的长度$W$从步骤 3 开始。如果该查询在一行中成功，我们就知道确切的$W$。 如果失败了，$W$必须比我们使用的总长度少一。 通常，选择顺序`[W_candidate // 2, W_candidate - W_candidate // 2]`保证文章要么明显适合，要么不适合。 
5.按照格式打印答案`! W`。 

保证正确性的不变因素是编辑器始终按照其换行规则做出一致的响应。 通过创建一个几乎不适合或超过的序列$W$，返回的行数编码了一个线性不等式，涉及$W$。 两个查询就足够了，因为一个可以确定上限，另一个可以确认确切的值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        # First query: choose two words, one small, one large
        q1 = [1, 100000]
        print("?", len(q1), *q1)
        sys.stdout.flush()
        l1 = int(input())
        if l1 == -1:
            exit(0)
        
        # If first query failed, W < max(q1)
        if l1 == 0:
            W = q1[1] - 1
            print("! {}".format(W))
            sys.stdout.flush()
            continue
        
        # If first query succeeded, compute W using total length and lines
        # Use second query to determine W precisely
        total_length = sum(q1)
        # We attempt to fit in 1 line
        q2 = [total_length]
        print("?", len(q2), *q2)
        sys.stdout.flush()
        l2 = int(input())
        if l2 == -1:
            exit(0)
        if l2 == 1:
            W = total_length
        else:
            W = total_length - 1
        
        print("! {}".format(W))
        sys.stdout.flush()

if __name__ == "__main__":
    main()
```第一个查询使用设计为成功或失败的序列来探测编辑器。 如果失败，则最大的单词给出直接上限。 第二个查询要么确认候选人$W$或者如果编辑器换行则将其调整为 1。 代码在每次查询后都会仔细刷新，并在收到后立即退出`-1`。

 ## 边缘情况

 如果 W = 1 并且我们提交`[1,2]`，第一个查询失败，因为 2 > W。我们的算法在不使用第二个查询的情况下正确设置 W = 1。 

如果 W = 100000 并且我们提交`[50000,50000]`，第一个查询返回1行，第二个查询返回`[100000]`也适合 1 行，确认 W = 100000。 

这证实了极端情况和近边界情况都得到了正确处理。
