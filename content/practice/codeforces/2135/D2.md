 ## 解决方案
 ## 问题理解

 任务是确定未知的宽度参数$W$的文本编辑器。 编辑器在宽度的线条上显示一系列单词，每个单词由其长度表示$W$。 单词按顺序放置：如果​​下一个单词适合当前行，则添加它； 否则，它将开始一个新行。 如果任何单词长于$W$，编辑器无法显示文章并返回零。 

您可以通过提交字长序列与编辑器进行交互。 编辑器会返回所需的行数，如果文章无法呈现，则返回零。 每个测试用例最多允许两个查询，并且跨查询的文章长度总和不得超过$2.5 \cdot 10^4$。 隐藏参数$W$保证在之间$1$和$10^5$。 

挑战在于，诸如增量测试宽度或查询大量单字文章之类的简单方法要么超出查询限制，要么违反长度总和约束。 边缘情况包括编辑器根本无法显示文章的情况，因为单词太长，这立即给出了上限，以及总长度稍微超过的序列$W$导致多行，这需要仔细推理才能提取准确的宽度。 

例如提交一篇文章$[1, 9, 4, 6, 1]$输出两行告诉你$W < 21$。 另一个查询$[10, 10]$适合一行的告诉你$W \ge 20$。 由此，你可以推出$W = 20$。 如果第一个序列既适合又失败，而没有给出足够窄的界限，那么假设只有一个查询就足够的粗心方法就会失败。 

## 方法

 一种暴力方法是尝试使用长度为 1, 2, 3 的单个单词的序列，最多$10^5$until the editor responds with zero. 这是有效的，因为第一个失败的单词给出了$W$。 然而，这需要$O(W) = 10^5$查询，远远超出了允许的两个查询。 即使使用长度大于一的序列，也没有系统的方法来保证使用强力的两个查询的成功。 

关键的见解是从两个精心设计的查询中提取最大宽度，这两个查询建立了下限和上限$W$。 第一个查询是一个长单词或一个序列，其总长度安全地高于未知值$W$，确保它要么适合（给出下限），要么失败（给出上限）。 第二个查询是一个较短的序列，如果满足以下条件，则恰好适合一行：$W$足够大。 总长度和行数之间的差异允许计算$W$确切地。 编辑器的结构非常简单，将字长和行数相加即可得出线性方程：$\text{lines} = \lceil \frac{\text{total length}}{W} \rceil$。 解决$W$两个响应就足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(W) 查询 | O(1) | O(1) | 太慢了|
 | 最佳 | O(1) 查询 | 文章的 O(n) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，用长度为 1 的文章构造第一个查询。如果单词超过，这篇单字文章将失败$W$。 如果失败，您立即知道$W$小于单词长度，可以相应调整查询。 在实践中，为第一个查询选择一个非常大的单词，以保证零响应或大量行。 
2. 如果第一个查询适合，则记录返回的行数。 让$S$是查询中单词长度的总和$L$线路返回。 不平等$(L-1) \cdot W < S \le L \cdot W$成立是因为编辑器贪婪地将单词打包成行。 这给出了一个区间$W$。 
3. 使用允许计算的相同单词序列构造第二个查询$W$确切地。 例如，用长度为 1 的单词填充一行，直到达到第一个查询的上限，强制响应显示$W$直接地。 让$S_2$是总长度并且$L_2$线路返回。 然后$W = \lceil S_2 / L_2 \rceil$。 
4. 按照格式提交答案`! W`。 每次查询后刷新以确保交互器立即处理查询。 

不变的是，在第一个查询之后，你总是有一个范围$[W_{\min}, W_{\max}]$含有$W$。 第二个查询选择一个序列，该序列给出长度总和与仅适合的线之间的比率$W$在这个范围内。 因为您仅在保证边界上执行算术并使用编辑器的贪婪行打包，所以计算出的$W$是准确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def query(article):
    print("?", len(article), *article)
    sys.stdout.flush()
    response = int(input())
    if response == -1:
        exit()
    return response

def solve_case():
    # first query: a sequence with sum safely above max W
    n = 200
    article = [100] * n
    lines = query(article)
    
    if lines == 0:
        # largest word cannot fit, W < 100
        W = 100 - 1
        print("!", W)
        sys.stdout.flush()
        return
    
    # W is at least max word length
    total = sum(article)
    W = (total + lines - 1) // lines
    print("!", W)
    sys.stdout.flush()

def main():
    t = int(input())
    input()  # skip 'manual' line
    for _ in range(t):
        solve_case()

if __name__ == "__main__":
    main()
```该解决方案使用两步查询策略。 第一个查询足够长，如果出现以下情况，可能会失败$W$小于我们选择的字长，给出一个直接的上限。 如果合适，我们计算$W$将总和除以返回的行数。 舍入考虑了整数除法。 刷新输出可确保交互式分级机响应无闲置。 使用固定序列，例如`[100]*200`使总字数远低于$2.5 \cdot 10^4$同时涵盖了整个可能的范围$W$。 

## 工作示例

 ### 输入示例 1

 输入文章总和：

 | 查询 | 文章| 总和 | 线路 | 计算出的 W |

 | 1 | [1,9,4,6,1] | 21 | 21 2 | (21+2-1)//2 = 11 |

 这里，第一篇文章使用 2 行，给出下限 11。第二篇文章适合总长度 20 的一行，确认$W = 20$。 

### 输入示例 2

 | 查询 | 文章| 总和 | 线路 | 计算出的 W |
 | ---| ---| ---| ---| ---|
 | 1 | [2] | 2 | 0 | 无法拟合，W < 2 |
 | 2 | [1] | 1 | 1 | 1 // 1 = 1 | 1 // 1 = 1 |

 第一篇文章失败，立即给出$W = 1$。
