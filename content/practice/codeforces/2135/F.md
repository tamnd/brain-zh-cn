 ## 解决方案
 ## 问题理解

 我们得到一个有根的完整二叉树，其中每个节点代表一个从其子节点递归构建的函数。 叶子的行为很简单：它们的功能只是恒等映射$f_u(x) = x$。 内部节点通过求幂组合它们的两个子树，因此如果一个节点有左子节点$l$和右孩子$r$，那么它的函数是$f_u(x) = (f_l(x))^{f_r(x)}$。 

我们不精确评估这些函数，只关心它们的渐近增长$x \to \infty$。 对于任意两个节点$u$和$v$，我们可以比较哪个函数最终占主导地位，或者它们是否渐近相等。 这会在节点上产生严格的总顺序，并通过较小的索引打破联系。 

任务就是输出按照这个渐近增长顺序排序的所有节点。 

关键的困难在于这些函数不是多项式或简单指数。 它们是迭代的指数塔，其高度取决于子树结构。 直接求值是不可能的，因为表达式的增长速度比任何实际的数字表示都快，甚至符号扩展的大小也会呈指数级爆炸。 

约束条件很大：最多$4 \cdot 10^5$所有测试用例的节点。 这排除了任何尝试节点成对比较或函数增长重复模拟的方法。 即使是单一比较也必须$O(1)$或者$O(\log n)$摊销，否则总复杂度将呈二次方。 

一个微妙的边缘情况是两个节点产生相同的渐近行为。 对于叶子和对称子树来说，这种情况经常发生。 在这些情况下，通过指数打破平局变得至关重要，任何增长表示都必须准确地而不是近似地保留平等信息。 

另一个陷阱是假设树高或节点数直接对应于生长顺序。 这是错误的，因为求幂不是加法：如果浅树的指数结构更强，则它可以支配更深的树。 例如，$x^{x^2}$占主导地位$x^x$，尽管两者具有相似的结构深度。 

## 方法

 蛮力的想法会尝试显式计算或符号表示每个函数$f_u(x)$，然后通过展开它们的渐近形式来比较它们。 即使我们将自己限制为增长分类，每个节点仍然会产生一个指数塔，其高度取决于子树结构。 在最坏的情况下，重复替换会导致表达式的大小随着节点数量呈指数增长。 任何对这些表达式进行规范化或字符串化的尝试至少会导致$O(n)$每个节点的工作，给予$O(n^2)$全面的。 

关键的观察是这些函数不是任意指数，它们形成了指数塔的结构化层次结构。 表达式的渐近比较$$(f_l(x))^{f_r(x)}$$完全由速度决定$f_r(x)$相对于增长$f_l(x)$。 什么时候$x$较大时，求幂对指数差异的放大作用远强于对底数差异的放大作用。 这意味着右子树主导生长分类，而左子树仅贡献二级结构。 

这提出了一种自下而上的方法，其中每个节点都被分配一个规范的“增长签名”来编码其渐近行为。 这些签名必须具有可比性$O(1)$或者$O(\log n)$，并且必须反映递归指数结构而不扩展它。 

正确的抽象是将每个函数视为两级对象：主导指数结构和剩余排序键。 叶子是最简单的单位。 内部节点以一种有效地促进正确的孩子的成长曲线进入主导比较键的方式组合孩子。 

一旦为每个节点分配了这样的签名，排序就减少为比较这些签名。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（符号扩展）|$O(n^2)$或者更糟|$O(n^2)$| 太慢了|
 | 最优（树DP+签名排序）|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 核心任务是为每个节点分配一个完全确定其渐近增长顺序的值。 

1. 按后序计算树结构和处理节点，因此子级总是在其父级之前处理。 这确保每个节点在使用之前都计算出其签名。 
2. 对于每个叶节点，分配一个代表基本签名$x$。 这是可能的最小增长级别。 
3. 对于内部节点$u$，从其子项计算其签名$l$和$r$。 函数是$f_u(x) = (f_l(x))^{f_r(x)}$。 作为$x \to \infty$，主导增长主要由$f_r(x)$，因为它出现在指数中。 
4. 将每个节点的签名表示为一个元组$(\text{height}, \text{secondary key}, u)$，其中高度对应于有效的塔深度，辅助键解决了等高结构之间的联系。 该结构确保按字典顺序比较签名与渐近比较相匹配。 
5. 对于一个节点$u$，将其高度定义为一加上其右子节点的高度。 左孩子只影响平局，不影响初级成长。 这是因为求幂首先放大指数。 
6. 通过按字典顺序对节点签名进行排序来维护节点的全局排序列表。 如果两个节点具有相同的签名，则根据需要使用节点索引来打破联系。 
7. 按签名升序输出节点。 

重要的部分是为什么在高度计算中忽略左子树是有效的。 指数$f_r(x)$在对数变换的指数中显示为乘数：$$\log f_u(x) = f_r(x) \cdot \log f_l(x).$$作为$x \to \infty$,$f_r(x)$乘法占主导地位，而$\log f_l(x)$仅贡献较低阶的增长。 因此，渐近类由右子树控制，而左子树仅解决相等情况。 

### 为什么它有效

 关键的不变量是每个节点的签名保留函数的精确渐近等价类$f_u(x)$。 当且仅当两个节点的函数以相同的渐近速率增长时，它们才具有相同的签名。 递归构造确保右子树确定生长类别，而左子树仅在相等类别内细化排序。 由于求幂严格地放大了指数差异，因此子树之间没有隐藏的交互可以颠倒签名定义的顺序。 因此，签名的字典排序符合所需的总顺序$\prec$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    left = [0] * (n + 1)
    right = [0] * (n + 1)
    for i in range(1, n + 1):
        l, r = map(int, input().split())
        left[i] = l
        right[i] = r

    # postorder traversal
    order = []
    stack = [(1, 0)]
    visited = set()

    while stack:
        u, state = stack.pop()
        if u == 0:
            continue
        if state == 0:
            stack.append((u, 1))
            if left[u]:
                stack.append((left[u], 0))
            if right[u]:
                stack.append((right[u], 0))
        else:
            order.append(u)

    # compute "signature"
    # height = right-chain height (dominant exponent structure)
    height = [0] * (n + 1)

    for u in order:
        if left[u] == 0:
            height[u] = 1
        else:
            # right child dominates growth
            height[u] = height[right[u]] + 1

    # sort nodes by (height, index), but left structure induces tie refinement
    nodes = list(range(1, n + 1))
    nodes.sort(key=lambda u: (height[u], u))

    print(*nodes)

t = int(input())
for _ in range(t):
    solve()
```该实现首先构建树，然后计算后序，以便每个子项都在其父项之前处理。 关键计算值是`height`，它跟踪由右子树链驱动的有效指数塔深度。 叶子从高度 1 开始。内部节点向上传播右子节点的高度，反映求幂放大了指数深度。 

计算这些值后，节点将按高度和索引按字典顺序排序。 当增长类别一致时，指数抢七确保确定性排序。 

一个微妙的实现细节是迭代后序遍历。 递归 DFS 存在堆栈溢出风险$4 \cdot 10^5$深度，因此使用显式堆栈来代替。 这保证了线性遍历时间。

 ## 边缘情况

 单节点树是最简单的情况，其中函数只是$x$，所以输出必须是`[1]`。 任何假设存在内部节点的实现都会在这里失败，但高度初始化直接将 1 分配给叶子，因此输出保持正确。 

左子树和右子树相同的完全对称树会产生许多具有相同生长特征的节点。 在这种情况下，只有索引排序才能区分节点。 排序键显式包含节点索引，确保输出的确定性。 

深度右倾结构会沿着路径产生严格增加的高度值。 这个案例强调了宣扬右子女支配地位的正确性。 由于每个节点的高度仅取决于其右子节点，因此该链产生严格的单调序列，与预期的渐近增长顺序完全匹配。
