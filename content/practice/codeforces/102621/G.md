 ## 解决方案
 ## 问题理解

 该问题是一个交互式任务。 隐藏对象是由 62 个字符集中的不同字符组成的密码，其中包含小写字母、大写字母和数字。 查询向法官发送一个可能的密码，法官回复查询是否是准确的密码、密码的正确子序列，或者根本不包含在密码中。 目标是在 750 次猜测之内找到密码。 

关键限制是每个字符最多出现一次，因此密码是字母表子集的排列。 最大可能长度为 62，这个长度足够小，可以对字符进行对数搜索，但不足以尝试所有可能的排列。 可能的密码数量是巨大的，因此任何基于枚举候选者的方法都是不可能的。 

棘手的部分来自于正确解释法官的反应。 包含一个字符的查询不仅仅告诉我们该字符。 它还显示整个密码的长度是否为一。 例如，查询`a`反对密码`a`给出`C`，查询时`a`反对`ab`给出`Y`。 将两个响应视为相同会丢失长度信息。 

另一个微妙的情况是最终查询。 如果我们构建的字符串以正确的顺序包含密码的每个字符，则答案可能是`C`而不是`Y`。 该算法必须立即停止`C`，因为成功后不允许发送额外的查询。 

## 方法

 一种直接的方法是尝试候选字符串并使用响应来消除不可能的密码。 这是正确的，因为每个答案都提供有关隐藏字符串的信息，但搜索空间太大。 即使将我们限制为没有重复字符的字符串也会给出$$62! + 62 \cdot 61! + \dots$$可能的密码，这远远超出了 750 次查询所能测试的范围。 

有用的观察是法官可以回答后续问题。 首先，我们可以通过询问每个字符来准确发现密码中存在哪些字符。 之后，剩下的问题就是对这些字符进行排序。 

由于字符是唯一的，一旦我们知道字符集，密码就只是它们的一个顺序。 我们可以维护密码的排序前缀并将新字符插入到正确的位置。 对插入位置的二分搜索之所以有效，是因为候选排序要么是子序列，要么不是。 这减少了从二次排序到粗略排序所需的查询数量$62 \log 62$。 

蛮力之所以有效，是因为每个有效的猜测都会提供信息，但它会失败，因为可能的订单数量会爆炸。 后续检查揭示了相对顺序的观察结果让我们可以用构造代替猜测。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(可能的密码数量) | O(候选人数量) | 太慢了|
 | 最佳| O(62 log 62) 查询 | 奥(62) | 已接受 |

 ## 算法演练

 1. 查询允许的字母表中的每个字符。 如果答案是`Y`，该字符属于密码。 如果答案是`C`，密码由该单个字符组成，我们可以立即完成。 
2. 将发现的字符按照迄今为止发现的顺序保留。 第一个已知字符开始当前有序序列。 
3. 将所有剩余的发现字符插入到当前序列中。 要测试位置是否正确，请将新字符放在那里并查询整个序列。 肯定的答案意味着该顺序与隐藏密码一致。 
4.插入时使用二分查找。 如果将字符放在中间位置之前有效，那么答案就在左半部分。 否则它必须在该位置之后。 
5. 每次插入后，维护的序列是真实密码的子序列。 插入所有字符后，序列等于密码，因此下一次成功查询将返回`C`。 

为什么它有效：不变的是所维护的序列始终以相同的顺序出现在隐藏密码中。 插入新字符时，只有一个位置保留此属性，因为密码没有重复字符。 二分查找仅使用有效的子序列检查在位置之间进行选择，因此它不能丢弃真实位置。 放置所有字符后，维护的序列包含密码的每个字符，因此必须是密码本身。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

alphabet = "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789"

def solve():
    def ask(s):
        print(s, flush=True)
        return input().strip()

    present = []

    for c in alphabet:
        res = ask(c)
        if res == "C":
            return
        if res == "Y":
            present.append(c)

    if not present:
        return

    order = [present[0]]

    for c in present[1:]:
        lo, hi = 0, len(order)

        while lo < hi:
            mid = (lo + hi) // 2
            candidate = ''.join(order[:mid]) + c + ''.join(order[mid:])
            res = ask(candidate)

            if res == "C":
                return

            if res == "Y":
                hi = mid
            else:
                lo = mid + 1

        order.insert(lo, c)

    res = ask(''.join(order))
    if res == "C":
        return

if __name__ == "__main__":
    solve()
```这`ask`函数处理交互协议。 它打印一个查询，立即刷新，并读取判断响应。 需要刷新是因为法官在收到完整的询问之前无法回答。 

第一个循环识别字符集。 一个字符接收`Y`保证位于密码中的某个位置，因为单个字符子序列仅在该字符存在时才能存在。 

插入部分保留`order`每次操作后有效。 从左侧部分、插入的字符和右侧部分重建候选字符串，避免索引错误。 二分搜索边界表示从零到当前长度的可能插入位置。 

最终查询按照重构顺序使用所有发现的字符。 如果算法正确，这就是隐藏密码，判断返回`C`。

 由于原始任务是交互式的，因此示例是对话而不是固定的输入/输出对。 

对于隐藏密码`hunter2`，角色发现阶段可能如下所示：

 | 步骤| 查询 | 回应 | 已知人物 |
 | --- | --- | --- | --- |
 | 1 |`h`| 是 | 小时 |
 | 2 |`u`| 是 | 嗯，你|
 | 3 |`n`| 是 | h,u,n |
 | 4 |`t`| 是 | h、u、n、t |
 | 5 |`e`| 是 | h、u、n、t、e |
 | 6 |`r`| 是 | h、u、n、t、e、r |
 | 7 |`2`| 是 | h,u,n,t,e,r,2 |

 排序阶段通过测试子序列来插入字符。 例如，当插入`t`进入`hun`，查询`thun`失败是因为`t`之前没有出现过`h`， 尽管`hunt`成功是因为它与隐藏顺序匹配。 

这表明子序列查询可以用作可能位置之间的比较操作。 

对于单字符密码，例如`A`，第一个字符查询给出：

 | 步骤| 查询 | 回应 | 行动|
 | --- | --- | --- | --- |
 | 1 |`a`| 尼 | 继续 |
 | 2 | ... | ... | 继续 |
 | 28 | 28`A`| C | 完成 |

 这证实了为什么算法必须处理`C`在字符检测阶段。

 ## 边缘情况

 对于单字符密码，例如`x`, 查询`x`回报`C`， 不是`Y`。 该算法立即退出，而不是尝试继续构建排序。 

对于包含按与实际位置不同的顺序发现的字符的密码，插入阶段会修复顺序。 例如，如果发现发现`a`,`b`,`c`但密码是`cab`, 插入`c`然后测试位置确保最终序列变为`cab`。 

对于包含所有可能字符的最大长度密码，该算法仍然有效，因为每次插入仅依赖于子序列检查。 查询数量随着字符数量的增加而增加，而不是随着可能的密码数量的增加而增加。
