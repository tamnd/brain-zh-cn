 ## 解决方案
 ## 问题理解

 我们给出了一系列的日子，每一天都标记为下雨（1）或好（0）。 Jean 希望完成尽可能多的徒步旅行。 每次徒步旅行恰好需要`k`连续几天的好天气，完成一次徒步旅行后，他必须至少休息一天，然后才能开始另一次徒步旅行。 该问题要求我们确定他在这几天的序列中可以适应的最大徒步次数。 

输入可以很大：最多`10^5`每个测试用例的天数最多`10^4`测试用例，所有测试用例的天数总和不超过`10^5`。 这意味着任何解决方案都必须以相对于天数的线性时间运行。 在几天范围内迭代的二次或嵌套循环会太慢。 

不明显的边缘情况包括间歇性降雨的序列，这会破坏可能的徒步旅行，序列`k`大于连续好天数，以及所有天都下雨或所有天都好的序列。 例如，如果`n = 5`,`k = 2`， 和`a = [0, 1, 0, 0, 0]`，一个天真的贪婪者，每跳一次`k`不检查中间休息的日子可能会多算加息。 

## 方法

 暴力方法会尝试每天开始加息`i`并检查是否有下一个`k`日子一切都好。 如果是，我们将增加加息计数并跳至当天`i + k + 1`为下一次潜在的加息做好准备。 这是有效的，因为它尊重强制休息日。 然而，这需要检查`k`每个可能的开始日的天数，导致最坏情况的复杂性`O(n * k)`。 对于大型`n`和`k`，这可以达到`10^10`操作，这是不可接受的。 

关键的观察是我们不需要重复地重新检查重叠的段。 相反，我们可以计算单次遍历中连续好天数。 每次我们找到一个块`length`连续的零，该区块中可以执行的加息次数为`length // k`。 该区块内的每次徒步旅行自然都会遵守强制休息日，因为我们可以在概念上在每次徒步旅行后放置一个“1”，从而有效地减少可用长度。 这将问题简化为阵列的单个线性扫描，在给定约束的情况下这是最佳的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n * k) | O(1) | O(1) | 对于大的 n 和 k 来说太慢 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化变量`count`为零以存储当前测试用例的加息次数。 初始化一个变量`length`为零以跟踪当前连续好日子的记录。 
2. 迭代数组中的每一天。 如果日子好的话（`a[i] = 0`), 增量`length`。 如果当天下雨（`a[i] = 1`）， 重置`length`为零。 这保持了不变量`length`总是代表当前连续的好日子块结束于`i`。 
3. 每当`length`达到`k`，我们可以安排徒步旅行。 增量`count`一个。 然后，为了强制执行强制休息日，减少`length`经过`k + 1`。 减法有效地跳过了远足所用的天数加上休息日，从而保持`length`准备好计算剩余几天内的下一次潜在加息。 
4. 继续迭代，直到数组末尾。 迭代结束后，`count`保存测试用例的最大加息次数。 
5. 打印`count`对于每个测试用例。 

这样做的原因是，该算法维持了连续好日子的长度，并在达到完整块大小时贪婪地安排加息`k`可用。 减法`k + 1`确保下次加息遵守强制休息日，无需重新扫描或重叠路段。 没有错过有效的加息，也没有违反规则的加息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    count = 0
    length = 0
    for day in a:
        if day == 0:
            length += 1
            if length >= k:
                count += 1
                length -= k + 1
        else:
            length = 0
    print(count)
```第一行读取测试用例的数量。 对于每个测试用例，我们阅读`n`和`k`然后是数组`a`。 主循环每天都会迭代，更新当前的好天气。 当可能加息时，我们会增加`count`并通过减少休息日来强制执行`length`。 重置`length`下雨天确保我们永远不会尝试恶劣天气的徒步旅行。
