 ## 解决方案
 ## 问题理解

 该任务要求我们找到与给定数字至少共享一位十进制数字的最小非负整数。 对于每个测试用例，我们都会提供一个编号`x`，我们需要产生一个数字`y`这样一些数字`y`也出现在`x`。 数量`y`应尽可能小。 

输入由多个测试用例组成，最多1000个，每个数字`x`介于 1 到 1000 之间。这些界限是适度的，这意味着我们可以进行简单的操作，例如将数字转换为字符串、迭代其数字或直接尝试所有单位数字。 自从`x`最多四位数字长，将其数字存储在集合或数组中在内存方面是微不足道的。 

要考虑的边缘情况包括本身是个位数的数字。 例如，如果`x = 7`，最小的`y`是`7`本身。 粗心的方法可能会尝试从零开始循环数字并检查每个数字； 这会起作用，但它太过分了并且忽略了这样一个事实：`y`必须始终是其中出现的数字之一`x`。 另一个微妙的情况是包含零的数字，例如`x = 102`，其中最小的`y`是`0`， 不是`1`或者`2`必然，但无论数字中最小的`x`。 

## 方法

 蛮力方法是从`y = 0`并逐步检查每个数字，看看它是否与`x`。 为了实现这一点，我们可以将两个数字都转换为字符串，然后检查每对数字是否相等。 在最坏的情况下，`y`在找到匹配项之前可能会达到 1000，并且重复进行字符串比较会使这种方法比必要的速度慢。 尽管对于给定的约束它仍然通过，但它并不优雅或概念上最小。 

关键的见解是`y`只需要为一位数，因为如果`x`存在于0-9之间，该数字已经是最小可能的数字`y`。 问题简化为提取数字`x`并返回最小的一个。 这是可行的，因为个位数是最小的非负整数，所以最小解就是出现在的最小数字`x`。 这种洞察力避免了任何不必要的迭代，并为每个测试用例提供了直接的、恒定时间的解决方案。

 ## 算法演练

 1.读取整数`t`，测试用例的数量。 
2. 对于每个测试用例，读取整数`x`。 
3. 转换`x`到一个字符串，以便我们可以迭代它的数字。 
4. 提取所有数字`x`并将它们转换为整数。 
5. 找出这些整数中最小的数字。 这是最小的`y`与共享一个数字`x`。 
6. 打印当前测试用例的最小数字。 

为什么有效：任何数字`y`与共享一个数字`x`必须包含其中出现的数字之一`x`。 由于数字 0-9 是整数的最小组成部分，因此最小`y`保证是最小的数字`x`。 这个不变量总是正确的，因为我们从不考虑数字之外的数字`x`，所以不小于有效值`y`可以存在。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    x = input().strip()
    digits = [int(d) for d in x]
    print(min(digits))
```该解决方案首先读取测试用例的数量。 对于每个测试用例，它将数字转换为字符串以轻松提取数字，然后将每个数字转换回整数以进行比较。 立即打印最小数字。 这可以避免不必要的循环，正确处理前导零，并且适用于单位数和多位数字。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        x = input().strip()
        digits = [int(d) for d in x]
        output.append(str(min(digits)))
    return "\n".join(output)

# Provided samples

 ## 边缘情况

 对于`x = 102`，数字是`[1, 0, 2]`。 该算法提取这些数字，找到最小值 (0)，然后将其返回。 虽然`y`可以是更大的数字，如 10 或 12，共享一个数字的最小非负整数是 0，并且算法可以正确生成该数字。 

为了`x = 1000`, 数字`[1, 0, 0, 0]`产量 0 为最小。 这证实了该解决方案可以正确处理多个零。 

对于个位数`x`，如 7，数字`[7]`直接产生 7，证实该算法对于小数无需附加条件即可工作。
