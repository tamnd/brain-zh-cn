 ## 解决方案
 ## 问题理解

 我们有几个独立的游戏。 每个游戏都由多堆石子组成。 两名玩家轮流进行，从曼迪开始。 在一个回合中，玩家恰好选择一堆，从中移除至少一个石子，然后立即应用全局规则：系统中的每一堆都将其大小加倍。 

从整个系统中移走最后一个剩余石头的玩家获胜。 如果比赛继续进行了非常多的步数，则比赛被宣布为平局。 

关键的困难在于，状态不仅依赖于移除，还依赖于每次移动后的乘法增长步骤。 即使清除后堆变小，在清除之前它也可能会再次生长。 

约束条件很大：所有测试用例的桩总数可以达到一百万，并且测试用例最多可以有十万个。 这立即排除了任何随着时间的推移或每次移动推理的模拟。 任何解决方案都必须在桩数的大致线性时间内处理每个测试用例，并可能将整个游戏简化为紧凑的不变量。 

一种天真的方法可能会尝试模拟回合，重复选择一堆，减去一个值，然后将所有桩加倍。 这失败有两个原因。 首先，终止前的移动次数可能非常大，因为加倍会迅速增加值。 其次，状态空间会爆炸，因为每一步都会改变每一堆，即使是一步也是 O(n)，这太慢了。 

第二个微妙的失败案例来自局部思考。 例如，人们可能会认为只有奇偶性或总和才重要，但加倍会改变所有堆的规模，因此移除的时间比原始总数更重要。 

一个小的说明性边缘情况是单堆：

 输入：```
1
1
1
```曼迪移走了唯一的一块石头，游戏立即结束。 曼迪赢了。 但如果堆更大，或者如果在最后一次移除之前进行加倍干预，结果就会发生巨大变化，表明操作顺序很重要。 

## 方法

 暴力模拟从字面上解释了游戏。 我们维护桩的数组，并在每次移动时尝试所有可能的移除，然后将所有桩乘以二。 即使我们只模拟一条最佳游戏路径，由于加倍，每次移动的成本都是 O(n)。 如果游戏持续 m 步，则复杂度变为 O(nm)。 由于值可以呈指数增长，因此 m 不受任何小多项式的限制，并且这种方法对于大输入会立即失效。 

关键的观察是，每次移动后乘以 2 可以在逆时针上解释为移位尺度。 我们不跟踪绝对堆大小，而是跟踪游戏进行时每块石头贡献的“有效未来单位”数量。 后来取出的石头价值更高，因为它会经历更少的加倍。 

这表明将问题转化为位置评估系统。 每个移动对应一个时间步长，并且每个初始石头实际上都有一个重量，该重量取决于它最终被移除的时间。 最佳玩法简化为决定第一个玩家是否可以强制轮到他们的最后一个有效单位。 

然后，该游戏就相当于 Nim 的变体，其中每个堆随着时间的推移贡献一个二进制结构。 加倍操作会改变所有贡献，因此重要的是移除的相对顺序而不是绝对值。 这将系统折叠成一个基于奇偶校验的游戏，通过变换后的堆大小表示来实现。 

一旦减少，结果仅取决于标准化 2 的幂后初始堆的组合二进制结构，从而导致标准化值的简单 XOR 式不变量。 获胜者取决于生成的类似 nim 的状态是否为零或非零，以及当过程需要超过允许的轮数时的特殊平局条件。

 ## 算法演练

 我们将每一堆解释为对全局类似 nim 状态的贡献，但我们必须首先消除重复加倍的影响。 由于每次移动都会将所有牌堆乘以 2，因此我们从每个值中分解出 2 的幂，这样只有奇数分量才重要。 

我们按如下方式进行。 

1. 对于每一堆，分解出 2 的所有幂并仅保留奇数部分。 这隔离了不变信息，因为加倍只会改变幅度，但不会改变奇数结构。 
2. 使用 XOR 组合所有标准化桩值。 这反映了经典的 Nim 推理，其中每堆在归一化后都独立地对 Grundy 值做出贡献。 加倍操作确保幅度缩放是无关的，因此仅保留结构组件。 
3. 如果所有归一化堆的 XOR 为零，我们就得出第二个玩家 (brz) 获胜的结论。 否则，曼迪获胜。 
4. 如果问题对移动次数施加硬限制（514114 轮），并且游戏将继续超出该范围，我们将结果分类为平局。 实际上，只有当状态导致在有限时间内不强制删除终端的循环时，才会发生这种情况。 

这样做的原因是，加倍保留了未来状态的相对顺序，但在反向时间观察时并没有改变有效贡献的均等性。 每个堆的行为就像一个 Nim 堆，其大小由其奇数核心决定，指数增长只会延迟但不会改变基本的 XOR 结构。 因此，该博弈简化为具有保留的格伦迪不变量的标准公正组合博弈。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        arr = list(map(int, input().split()))
        
        x = 0
        for v in arr:
            while v % 2 == 0:
                v //= 2
            x ^= v
        
        if x == 0:
            print("brz")
        else:
            print("Mandy")

if __name__ == "__main__":
    solve()
```实现独立地处理每个测试用例。 对于每一堆，它都会重复地除以二的因数，只留下奇数部分。 这是至关重要的，因为所有偶数因子都是重复的全局加倍的产物，并且不携带任何战略信息。 

标准化后，我们对所有值进行异或。 此步骤对独立桩的 Sprague Grundy 和进行编码。 最终条件直接将异或零映射到第一个玩家的失败位置。 

由于元素总数可能达到一百万，因此必须注意有效地读取输入。 循环结构确保每个测试用例的处理时间为 O(n)，除了简单算术之外没有任何开销。 

## 工作示例

 考虑一个有两堆的小箱子。 

输入：```
1
2
3 5
```我们计算归一化：

 | 步骤| 桩| 异或状态 |
 | --- | --- | --- |
 | 开始| [3, 5] | 0 |
 | 堆1后| [3] | 3 |
 | 堆2后| [3, 5] | 3 异或 5 = 6 |

 最终 XOR 为 6，所以 Mandy 获胜。 

这表明，在去除 2 的幂后，独立堆贡献在 XOR 下线性组合，并且原始大小并不重要。 

现在考虑一个偶数结构的情况：

 输入：```
1
3
4 8 12
```标准化消除了两个的所有因子：

 | 步骤| 桩| 异或状态 |
 | --- | --- | --- |
 | 4 → 1 | [1] | 1 |
 | 8 → 1 | [1, 1] | 0 |
 | 12 → 3 | [1, 1, 3] | 3 |

 最终 XOR 为 3，所以 Mandy 再次获胜。 

这表明，即使大规模扩展的输入也会崩溃到其奇数核心，这证实了加倍除了扩展之外没有任何战略效果。

 ## 边缘情况

 单桩是最直接的边界。 如果堆中包含任何正数，曼迪可以在任何加倍对任何事情产生有意义的影响之前立即拿走所有石头。 该算法将数字减少到其奇数核心，该奇数核心不为零，因此 XOR 不为零，输出为 Mandy。 

对于像这样的情况`2 4 8`，每一堆都变成`1`去掉二的因数后。 三个一的异或是`1`，所以曼迪获胜。 这证实了缩放差异并不重要。 

对于完美平衡的情况，例如`1 1`，XOR 变为零，所以 brz 获胜。 加倍操作永远不会改变这个不变量，因为两个桩在缩放下的演变相同，从而在整个游戏结构中保留取消。
