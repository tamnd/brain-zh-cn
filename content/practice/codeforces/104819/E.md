 ## 解决方案
 ## 问题理解

 我们得到一个有向无环图，其中每个节点代表一个城市，每个城市都有一个数字魅力值。 旅行者必须沿着有方向的道路从城市 1 前往城市 n。 图结构保证不存在循环，因此每条有效路线都是 DAG 中的一条简单路径。 

如果一条路线沿途某处存在三个连续访问过的城市 x → y → z，且它们的魅力值之和很小，即 ax + ay + az ≤ k，则该路线被认为是不好的。 任务不是找到最佳路线或计算任何东西，只是确定是否存在至少一条从 1 到 n 的有效路径来避免这种禁止的三重条件。 

关键的困难在于约束不是边或节点对的局部约束，而是取决于沿路径的每个长度为 3 的滑动窗口。 这将标准 DAG 可达性问题转化为具有最后两个顶点内存的约束路径可行性问题。 

约束很大，每个测试最多有 3×10^5 个节点和边，以及最多 10^3 个测试用例。 这立即排除了任何尝试显式枚举路径的方法，因为即使是中等分支的 DAG 也会生成指数级的多条路径。 除非仔细压缩，否则即使对所有状态对或三元组进行动态规划也会太大。 

当 DAG 中存在一条路径但每种可能的延续都会强制至少有一个禁止的三元组时，就会出现一种微妙的极端情况。 另一个极端情况是路径非常短，这意味着它的节点少于三个，在这种情况下，不会触发任何限制，并且任何有效路径都会自动接受。 

## 方法

 暴力破解的想法很简单：探索从节点 1 到节点 n 的所有路径，并在每次扩展路径时检查最后三个节点是否违反条件。 由于该图是 DAG，因此路径上的 DFS 或 BFS 将终止，并且正确性是立即的，因为我们明确验证了每个候选路线的约束。 

问题是 DAG 中不同路径的数量可能是 n 的指数。 即使是每层有两个选择的简单分层图也会产生 2^(n/2) 条路径，这远远超出了任何可行的计算。 缺少的结构是，虽然路径很多，但条件仅取决于最后两个节点，而不取决于完整的历史记录。 

这建议将遍历的状态压缩为仅记住最后两个顶点的状态。 然而，状态 (u, v) 上的朴素 DP 意味着我们来自 u 的 v 会导致 O(mn) 或更糟糕的转换，在最坏的情况下仍然太大。 

关键的观察是我们没有优化任何东西，只是检查存在性。 因此，我们不需要跟踪所有可能的 (u, v) 对，而只需传播哪些对是可达的，同时修剪立即创建错误三元组的转换。 仅当 p + u + v > k 时，每个有向边 u → v 才能从状态 (p, u) 延伸。 

这将问题转化为提升图中的可达性，其节点是原始节点的有序对。 虽然该图在实践中最多可以有 m 个状态，但我们可以限制转换，以便每条边仅在形成有效扩展时才被处理。 因为图是 DAG，所以我们可以按拓扑顺序处理节点，并为每个节点 v 维护可以在不违反约束的情况下到达它的可能的先前节点 p 的集合。 

我们通过仅维护有效转换的邻接性来避免显式存储所有对，通过边缘有效地传播可达性，同时过滤掉无效的三元组。

 ## 算法演练

 1. 计算 DAG 的拓扑顺序。 这确保了当我们处理一个节点时，所有可能的前驱节点都已被考虑。 这种排序至关重要，因为过渡只能沿着有向边向前移动。 
2. 对于每个节点 v，维护一个记录所有有效前驱 p 的集合或邻接结构，使得存在以 p → v 结尾的路径，且不违反以 v 结尾的任何三元组的条件。这表示正确扩展路径所需的内存。 
3. 通过将节点 1 标记为可达且无前驱状态来进行初始化。 从概念上讲，我们允许只有一个节点的开始状态，因此还不能应用三重约束。 
4. 按拓扑顺序处理节点。 对于每个有向边 u → v，考虑 u 的每个有效前驱 p。 每个这样的对 (p, u) 表示以 u 结尾的路径的有效后缀。 
5. 对于每个这样的状态 (p, u)，通过验证 p + u + v > k 来检查添加 v 是否形成坏三元组。 如果它有效，那么我们可以扩展可达性并将 u 记录为 v 关于 p 的有效前驱。 
6. 继续向前传播这些转换，根据需要合并重复的状态。 关键是我们从不存储完整路径，只存储强制约束所需的最后两个顶点。 
7. 最后，检查节点 n 是否有任何有效的前驱状态可达。 如果是，则至少存在一条从不违反约束的完整路径。 

### 为什么它有效

 该算法保持这样的不变性：每个存储的对 (p, u) 对应于从 1 到 u 的真实路径，其每个连续的三元组都已被验证。 仅当新三元组 (p, u, v) 有效时才接受对 v 的任何扩展，因此不会引入无效路径。 由于按照拓扑顺序，每个可能的有效扩展都会被考虑一次，因此从 1 到 n 的任何有效路径最终都会以节点 n 的状态表示，从而确保完整性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import defaultdict, deque

def solve():
    T = int(input())
    for _ in range(T):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        g = [[] for _ in range(n)]
        indeg = [0] * n
        
        edges = []
        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            indeg[v] += 1
            edges.append((u, v))
        
        # topological sort
        q = deque([i for i in range(n) if indeg[i] == 0])
        topo = []
        while q:
            u = q.popleft()
            topo.append(u)
            for v in g[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    q.append(v)
        
        # dp[v] = set of possible predecessors p such that (p -> v) is valid suffix
        dp = [set() for _ in range(n)]
        
        dp[0].add(-1)  # virtual predecessor
        
        for u in topo:
            for v in g[u]:
                for p in dp[u]:
                    if p == -1:
                        # only two nodes so far
                        dp[v].add(u)
                    else:
                        if a[p] + a[u] + a[v] > k:
                            dp[v].add(u)
        
        if dp[n - 1]:
            print("Yes")
        else:
            print("No")

if __name__ == "__main__":
    solve()
```该代码首先读取图形并构建邻接列表以及拓扑排序的入度计数。 拓扑排序确保在处理节点时，已经考虑了到达该节点的所有方式。 

动态规划数组`dp[v]`存储可能出现在某个有效路径中紧邻 v 之前的所有可能节点，同时通过转换隐式记住上一步。 哨兵值`-1`表示长度为一的路径，其中尚不存在三重约束。 

在转换过程中，每条边 u → v 都会尝试扩展所有以 u 结尾的已知有效后缀。 如果后缀短于三个节点，我们总是接受转换。 否则，我们在允许传播之前显式检查总和条件。 

最后，答案取决于节点 n 是否存在任何有效的前驱状态。 

一个微妙的点是状态压缩是不对称的：我们只显式存储一级历史记录，并依赖 dp[u] 来表示 u 的所有有效前驱。 这是有效的，因为每个三重检查只需要 u 的直接前驱，它编码在 dp[u] 中。 

## 工作示例

 考虑一个简单的链 1 → 2 → 3，其中 a1 = 1、a2 = 2、a3 = 3 且 k = 10。 

我们从 dp[1] = {virtual} 开始。 在节点 1，我们传播到节点 2，将 1 加到 dp[2] 中。 在节点 2 处，由于前驱是虚拟的，因此我们接受到节点 3 的转换并将 2 添加到 dp[3] 中。 节点 3 可达，因此答案为“是”。 

| 节点| dp 状态 | 原因 |
 | ---| ---| ---|
 | 1 | {-1} | 开始 |
 | 2 | {1} | 第一次转变|
 | 3 | {2} | 还没有三重约束|

 现在考虑三重约束阻碍进展的情况：1 → 2 → 3 → 4，其中 a = [5, 5, 5, 5]，k = 12。 

在节点 3 处，三元组 (1,2,3) 已经给出 15，这违反了条件，因此 dp[3] 变为空，并且节点 4 无法到达。 

| 节点| dp 状态 | 有效转换 |
 | ---| ---| ---|
 | 1 | {-1} | 开始 |
 | 2 | {1} | 好的 |
 | 3 | {} | 被封锁 |
 | 4 | {} | 无法到达 |

 这表明，一旦中间节点的所有状态都失效，则任何延续都无法恢复。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 平均 O(n + m)，最坏 O(m·S) | 每条边仅传播有效的前趋状态 |
 | 空间| O(n + m) | 邻接加DP集|

 对于典型的 DAG 结构，该算法的边数是线性的，因为每个有效的状态转换仅创建一次。 考虑到每个测试最多 3×10^5 条边的约束，只要通过尽早修剪无效三元组来保持状态集的控制，这就可以很好地满足时间限制。

 ## 边缘情况

 长度为二的短路径永远不会触发约束。 例如，如果存在边，则具有任何值的 1 → 2 始终会产生“是”，因为不会形成三元组。 该算法可以处理此问题，因为 dp[2] 是使用虚拟前驱直接从 dp[1] 初始化的，完全绕过了三重检查。 

另一种情况是，一个节点存在多个前驱，但只有一个导致有效的延续。 该节点处的 dp 集可能包含多个候选者，但只有那些通过三重约束的候选者才会进一步传播。 这确保无效的历史不会污染未来的状态。 

最后一个微妙的情况是当 dp 变大时。 由于 dp 存储了前驱节点，因此它可以随着度数的增长而增长。 然而，每个存储的条目都对应于至少一个有效的路径前缀，并且通过集合语义自然地避免了重复，从而防止了冗余传播。
