 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，并且该序列通过点更新进行修改。 每次修改后，我们需要计算一个来自涉及多项式的相当不寻常的计数过程的值。 

多项式以标准方式定义为具有非负整数系数的无限形式和，尽管只有有限多个系数是非零的。 然后根据从数组中获取的某些值来评估每个多项式。 

对于固定多项式，我们查看数组中不同索引的所有有序对。 如果在第一个索引处存储的值处计算多项式恰好产生在第二个索引处存储的值，并且多项式系数都严格小于第一个索引处的值，则对有贡献。 

每次更新后的关键输出不是关于一个多项式，而是关于所有可能的有效多项式的贡献之和。 

所以输入是一个动态数组。 每次更新后，我们从概念上考虑每个具有非负整数系数的多项式，对于每个这样的多项式，我们计算它在评估下正确映射的索引对的数量，然后对所有多项式求和。 

这些约束促使我们寻求一种解决方案，在每次更新的恒定时间内重新计算答案。 如果更新多达二十万次，对数组或多项式结构的任何每次查询重新计算都会太慢。 即使每个查询的 O(n) 也已经是临界值，并且任何涉及多项式计算或每对组合计数的事情都将远远不可行。 

一个微妙的点是系数的条件取决于该对的第一个索引。 这意味着根据使用哪个指数作为评估的输入，在不同的系数限制下考虑相同的多项式。 这是天真的解释容易出错的主要地方。 

一个常见的陷阱是假设多项式行为在很大程度上取决于系数的实际大小，或者不同的多项式以复杂的重叠方式做出贡献。 另一个错误是试图显式枚举多项式或将它们视为超出其诱导值映射的组合对象，这在时间限制下是不可能的。 

## 方法

 蛮力视角首先修复多项式并检查所有索引对。 对于每一对，我们在一个数组值处评估多项式并将其与另一个数组值进行比较，同时还根据第一个值检查系数约束。 即使我们将多项式次数限制为有限截止，系数分配的空间原则上也是无界的，甚至小截断也会发生组合爆炸。 这使得多项式的直接枚举完全不可行。 

关键的转变是停止考虑单个多项式，而是推理它们在系数限制下可能产生什么值。 具有非负整数系数的多项式本质上是一种基本表示机制：在某个点进行计算将系数转换为位置数字系统中的数字。 

如果我们计算值 c，则多项式将变为 a0 + a1 c + a2 c^2 + … 形式的和，其中 ai 被限制为非负且严格小于 c。 这正是使用 0 到 c−1 有效范围内的数字表示以 c 为基数的整数的定义，除了 c 为 0 或 1 时的简并情况。 

这一观察结果将无限多项式空间折叠成一个事实：对于固定的评估点 c，当 c ≥ 2 时，每个目标整数恰好具有一个有效的系数分配，而当 c 为 0 或 1 时，其行为非常有限。

一旦我们接受每一对贡献零个或恰好一个有效多项式，所有多项式的总和就减少为计算有多少对满足简单的可表示性条件。 

然后，问题就变成了纯粹的数组值组合问题：根据每个值是 0、1 还是至少 2 对每个值进行分类，并维护全局存在多少个零。

 | ---| ---| ---| ---|
 | 多项式的暴力破解 | 指数/无穷 | O(1) | O(1) | 不可能|
 | 价值分类+计数| O(n + q) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将每个数组值分为三个类别之一：零、一或至少二。 这是影响有多少多项式可以将一个索引映射到另一个索引的唯一属性。 
2. 维护两个全局计数器：数组中零的数量和至少为 2 的元素的数量。 
3. 对于每个索引 i，仅根据其值类别确定其对答案的贡献。 如果 ci 至少为 2，则它可以充当足够大的基，使得每个整数 cj 恰好具有一个有效的多项式映射，因此它为每个不等于 i 的 j 贡献一个有效的多项式映射。 如果 ci 为 1，则系数限制会强制所有系数为零，因此多项式完全相同为零，并且它仅匹配等于零的目标，这意味着它对数组中的每个零贡献一次。 如果 ci 为零，则没有多项式满足系数限制，因此它没有任何贡献。 
4. 合并所有指数的贡献以形成总答案。 值至少为 2 的索引各自贡献 (n−1)，等于 1 的索引贡献当前的零数量。 

这种简化背后的核心思想是，用有界系数对 ci 进行评估，将多项式转变为以 ci 为基数的数字系统。 当ci≥2时，该系统是完备的，并且在非负整数上是双射的，因此保证了存在性和唯一性。 当 ci 为 1 或 0 时，系统会退化，破坏对应关系并产生唯一的例外情况。 

不变量是，每个有效多项式为每对 (i, j) 贡献一个映射，其中 ci ≥ 2，否则贡献一个到零的映射，并且不存在隐藏的多重性，因为系数约束强制表示的唯一性。 这确保基于值类别的计数与所有多项式的总和完全匹配，而不会过度计数或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    c = list(map(int, input().split()))

    zeros = sum(1 for x in c if x == 0)
    ge2 = sum(1 for x in c if x >= 2)

    def recompute():
        return ge2 * (n - 1) + sum(1 for x in c if x == 1) * zeros

    ones = sum(1 for x in c if x == 1)

    # maintain full consistency via counts
    ones = sum(1 for x in c if x == 1)

    for _ in range(q):
        i, y = map(int, input().split())
        i -= 1

        old = c[i]
        if old == 0:
            zeros -= 1
        elif old == 1:
            ones -= 1
        else:
            ge2 -= 1

        c[i] = y

        if y == 0:
            zeros += 1
        elif y == 1:
            ones += 1
        else:
            ge2 += 1

        print(ge2 * (n - 1) + ones * zeros)

if __name__ == "__main__":
    solve()
```该实现依赖于隐式维护三个简单计数，即使最终公式中只严格需要两个计数。 值至少为 2 的索引的贡献仅取决于 n，因此它减少为固定乘数乘以它们的计数。 等于 1 的索引需要全局零计数，因此跟踪零至关重要。 

一个微妙的实现细节是在重新计算答案之前更新计数。 如果在插入新值之前未正确删除旧值，则零类别和一类别会发生漂移，从而在最终乘法中产生不正确的交叉项贡献。 

## 工作示例

 考虑一个长度为三的数组：[2,0,1]。 这里零 = 1，一 = 1。 

值为 2 的索引贡献 (n−1) = 2。值为 0 的索引贡献 0。值为 1 的索引贡献 0 的数量，即 1。总计为 3。 

现在处理一个更改，将第二个元素从 0 变为 2，给出 [2, 2, 1]。 现在零 = 0，一 = 1。 

两个 2 值索引各贡献 2，1 值索引贡献 0。总计变为 4。 

| 步骤| 数组| 零| 那些 | ge2 | 计算答案 |
 | ---| ---| ---| ---| ---| ---|
 | 初始| [2,0,1]| 1 | 1 | 1 | 3 |
 | 更新 | [2,2,1]| 0 | 1 | 2 | 4 |

 该跟踪显示答案的结构仅取决于类别计数，而不取决于超出其阈值分类的实际数值。 每个类别贡献的不变量在更新过程中保持稳定。

 ## 边缘情况

 当所有值都为零时，每个索引都属于禁止类别，其中没有多项式满足系数约束。 该算法正确地得出零，因为两个贡献项都消失了：没有 1，也没有大值。 

当所有值都为 1 时，系数限制会强制每个多项式崩溃为零多项式。 每个索引准确地贡献了零的数量，在本例中为零，因此在所有更新中答案仍然为零。 

当值在 1 和至少 2 之间振荡时，主导项在零计数缩放和 (n−1) 缩放之间切换。 由于该算法增量更新类别计数，因此它可以正确跟踪这些转换，而无需重新计算。
