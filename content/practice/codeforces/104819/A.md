 ## 解决方案
 ## 问题理解

 我们得到一个小写字符串，并要求计算它有多少个子字符串包含该模式`"sysu"`作为子序列。 子字符串是通过选择字符串的连续段来定义的，而子序列允许跳过字符而不改变顺序。 如果在子字符串内部，我们可以选择四个字符来拼写该子字符串，则该子字符串被认为是有效的`s → y → s → u`。 

输入长度最大可达一百万个字符。 任何尝试显式检查所有子字符串的解决方案都会立即被排除，因为大约有$O(n^2)$子串，甚至每个子串的线性扫描都会超出可行的限制许多数量级。 这促使我们采用一种方法，其中每个位置都以摊余常数或对数时间做出贡献。 

当字符串包含许多重叠出现的模式字符时，会出现微妙的边缘情况。 例如，在`"ssyyssuu"`，多个子字符串以不同的方式重用相同的字符位置来形成子序列。 如果没有正确考虑选择子序列索引的多种有效方法，则每个子字符串的天真贪婪扫描也可能会失败； 正确答案只取决于存在性，而不取决于唯一性。 

## 方法

 暴力策略会枚举每个子串$[l, r]$，并针对每一项检查是否`"sysu"`可以形成一个子序列。 检查单个子串的长度是线性的，因此总成本变为：$$\sum_{l=1}^{n} O(n-l) = O(n^2)$$这对于$n = 10^6$。 

关键的观察是，我们实际上不需要从头开始为每个子串重新计算子序列的可行性。 相反，我们扭转视角：固定结束位置$r$，并计算有多少个有效的起始位置$l$产生一个结束于的子字符串$r$。 

对于固定的右端点，我们希望所有左端点的子字符串包含以下子序列匹配`"sysu"`。 如果我们从左到右扫描字符串，同时保留有多少个部分匹配`"sysu"`在每个位置结束时，我们可以将问题转化为计算完整比赛完成了多少次以及有多少个较早的开始可以与之配对。 

表达这一点的标准方法是对模式状态进行动态编程。 让图案成为$p =$ `"sysu"`。 我们跟踪在扫描字符串时可以处于模式的每个前缀状态的有多少种方式（或有多少个起始锚点）。 当我们看到一个角色时，我们会更新模式中的过渡。 每次我们到达最终角色时`'u'`，我们已经形成了一个以当前索引结束的完整子序列，并且所有有助于达到状态 3 的有效起始位置都形成了在此结束的有效子串。 

问题归结为维护，对于字符串的每个前缀，我们可以匹配前缀的有多少种方式`"sysu"`作为在当前位置结束的子序列，并在我们完成模式时求和贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了 |
 | DP 模式状态 |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们对待`"sysu"`作为一个 4 状态自动机。 状态 0 表示我们没有匹配任何内容，状态 1 表示我们已匹配`'s'`，状态 2 意味着`"sy"`，状态3意味着`"sys"`，状态 4 表示已满`"sysu"`。 

1.初始化一个数组`dp`大小为 5 其中`dp[i]`代表我们与第一个匹配的方式有多少种`i`模式的字符作为子序列直到当前位置。 最初`dp[0] = 1`，表示空子序列，其他均为 0。这种设置确保我们可以在字符串中的任何位置开始匹配。 
2. 从左到右扫描字符串。 对于每个字符，我们从右到左更新 DP 数组，以便转换不会在一个步骤中多次重复使用同一字符。 这保留了子序列计数的正确性。 
3. 如果当前字符是`'u'`，我们可以扩展任何部分匹配`"sys"`进入一场完整的比赛`"sysu"`。 我们添加`dp[3]`进入`dp[4]`。 每个这样的扩展对应于早期索引的不同选择，这些索引形成在当前位置结束的有效子序列。 
4. 如果当前字符是`'s'`，它可以作为模式的第一个或第三个字符，具体取决于先前的匹配。 我们更新`dp[3] += dp[2]`和`dp[1] += dp[0]`。 顺序很重要，因为后续更新不得使用同一迭代中已修改的值。 
5. 如果当前字符是`'y'`，它可以延伸`"s"`进入`"sy"`，所以我们更新`dp[2] += dp[1]`。 
6. 处理完整个字符串后，答案是`dp[4]`，计算有多少个子序列等于`"sysu"`存在。 每个这样的子序列唯一对应于一个子字符串，其端点由第一个和最后一个选择的字符定义，因此该计数与良好子字符串的数量匹配。 

### 为什么它有效

 在每个索引处，`dp[k]`表示选择以当前位置结尾且与 length 前缀匹配的子序列的方式数`k`的`"sysu"`。 不变量是所有有效的子序列构造都只考虑一次，因为每个字符要么扩展先前的状态，要么被忽略。 由于更新始终沿着模式向前移动，并且不会在单个转换中重复使用同一字符两次，因此不会引入无效重叠。 每个完成的状态 4 对应于形成索引的唯一选择`"sysu"`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    # dp[i]: number of ways to form prefix of pattern "sysu" of length i
    dp = [0] * 5
    dp[0] = 1

    for ch in s:
        if ch == 's':
            dp[1] += dp[0]
            dp[3] += dp[2]
        elif ch == 'y':
            dp[2] += dp[1]
        elif ch == 'u':
            dp[4] += dp[3]

    print(dp[4])

if __name__ == "__main__":
    solve()
```该实现保留单个 DP 阵列并就地更新它。 关键的细节是，更新按每个角色的固定顺序应用，以便贡献不会在同一迭代中错误地重用。 该结构直接反映了模式的自动机转换。

 ## 边缘情况

 一个最小的字符串，例如`"s"`或者`"sy"`产生零，因为 DP 永远不会达到最终状态。 该算法通过离开来处理这个问题`dp[4]`在整个扫描过程中保持不变。 

像这样的字符串`"sysu"`显示一次最简单的成功转换所有状态，确认每个角色正确地推进自动机。 

严重重复的字符串，例如`"ssssyyyyuuuu"`锻炼积累行为。 每个`'s'`增加可能的起点，每个`'y'`部分乘法`"s"`匹配到`"sy"`，以及每个`'u'`最终确定组合。 DP 无需重新计算即可累积这些贡献，并且每个完成的状态都对应于一个有效的子序列，即使在最大重复次数下也能确保正确性。
