 ## 解决方案
 ## 问题理解

 我们给定一个大小矩阵$n \times m$，其中每行代表一个参与者，每列代表一项技能。 我们必须准确选择$m$不同的参与者并分配每个$m$特定选定参与者的技能位置。 一旦我们为参与者分配了技能排列，团队的分数就是所选值的总和$a_{s_i, t_i}$。 

关键的自由在于选择之后$m$参与者，我们可以排列哪个参与者对哪个技能维度做出贡献，并且我们选择使总和最大化的排列。 所以对于一组固定的$m$人，最优分配是人和技能之间的最佳二分匹配，使权重之和最大化。 

我们不仅必须输出最大可能的总和，而且还必须明确地将参与者分配给实现该总和的不同技能指数。 

这些限制迫使我们采取谨慎的结构。 该矩阵最多可以包含$2 \cdot 10^6$值总计，因此读取并处理每个值一次是可以接受的。 然而，$n$可以大到$1.5 \cdot 10^5$， 尽管$m \le 60$。 这种不对称性是关键：我们可以负担得起大致的算法$O(n m)$或者$O(m^2 \log n)$，但任何接近$O(n^2)$是不可能的。 

一个天真的方法是尝试所有子集$m$行并计算每个子集的最佳排列。 即使忽略排列，单独选择子集也是如此$\binom{n}{m}$，这是一个天文数字。 另一个幼稚的方向是尝试将每项技能独立地贪婪地分配给每列的最佳可用参与者，但这会失败，因为用于一项技能的参与者无法重复使用。 

贪婪列选择的一个微妙的失败案例是最佳值聚集在几行中。 例如，如果一行在许多列中是最好的，那么重复选择它是非法的，但是每列的贪婪方法恰恰会这样做并高估答案。 每行必须使用一次的约束创建了全局匹配约束，而不是独立的每列决策。 

## 方法

 如果我们将其重新解释为选择，问题就会变得更加清晰$m$行，然后计算这些行和$m$列。 这是大小二部图上的经典分配问题$m$，但是左侧不是固定的，我们必须选择哪一个$m$要激活的行$n$。 

如果我们修复行的子集$S$，最优得分是完全二部图中最大匹配的值$S$和列，其中边权重是$a_{i,j}$。 自从$m \le 60$，列上的匹配可以用 DP 或位掩码 DP 来处理$O(m 2^m)$，但我们无法对所有行子集运行它。 

关键的观察结果是，分配仅取决于已使用的列，而不取决于选择行的顺序。 这建议逐步构建解决方案，逐一添加行并保持最佳的部分匹配状态。 

我们在列的位掩码上定义 DP，其中 dp[mask] 是通过将前 k 个选定行分配给掩码中的列集可实现的最佳总和。 每个新行可以被忽略，也可以通过将其分配给一个未使用的列来改进匹配。 这导致了经典的“增量分配”DP，其中每行都被处理一次，并且转换尝试将其分配给空闲列。 

天真的版本会尝试对行的每个子集进行转换，从而导致指数爆炸。 我们的见解是，我们永远不需要重新访问旧行，并且每一行最多贡献一列，因此 DP 通过放松状态来演化，而不是从头开始重新计算。 

更精细的角度是，我们正在有效地选择$m$在所有行和列都不同的约束下的最佳行列配对。 自从$m$很小，我们维护一个结构，为每个列子集跟踪最多使用那么多行的最佳可能总和，并且我们贪婪地分配行以改进最佳状态。 

最终接受的方法是贪婪的动态构造：以任意顺序对行进行排序，在列的位掩码上维护 DP，并通过尝试将该行分配给任何列来为每行更新 dp。 这已经足够了，因为任何最佳解决方案都精确地使用$m$行，一旦其列选择固定，每行都会独立贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集 + 匹配 |$O(\binom{n}{m} \cdot m!)$|$O(m)$| 太慢了|
 | 行和列上的位掩码 DP |$O(n \cdot m \cdot 2^m)$|$O(2^m)$| 已接受 |

 ## 算法演练

 我们将问题视为逐步构建行和列之间的匹配，同时确保每列最多使用一次。 

1. 在所有列子集上初始化 DP 数组，其中 dp[mask] 存储通过将一些已处理的行精确分配给 mask 中的列可实现的最大总和。 我们从 dp[0] = 0 开始，所有其他状态均为负无穷大。 
2. 逐行处理。 对于每一行，我们计算它如何改进现有的 DP 状态。 该行要么不对团队做出贡献，要么被分配给恰好一个未使用的列。 
3. 对于每个现有掩码，我们尝试将当前行分配给不在掩码中的任意列 j。 这会转换 dp[mask | (1 << j)] 从 dp[mask] 到 dp[mask] + a[i][j]。 这编码了该行用作列 j 的所有者的决定。 
4. 我们必须小心地处理 DP 转换，以防止在一次迭代中多次使用同一行。 因此，我们按降序复制 DP 或迭代掩码，以避免过早覆盖状态。 
5. 我们对所有行继续此过程。 最后，我们看一下 dp[(1 << m) - 1]，它表示将所有列完全分配给不同的行。 
6. 为了重构分配，每当我们改进 DP 状态时，我们都会存储父指针，记录导致转换的行和列。 

为什么有效：每个有效的解决方案都对应于准确的选择$m$行并将它们双射分配给列。 DP 枚举了选择列子集并按某种顺序向它们分配不同行的所有方法。 每个状态仅对填充的列以及该配置的最佳可实现总和进行编码。 由于每个转换都保留了构造路径中每列最多使用一次且每行最多使用一次的不变量，因此任何可行的分配都是可表示的，并且DP始终保持所有表示中最好的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    INF = -10**30
    dp = [INF] * (1 << m)
    parent = [(-1, -1, -1)] * (1 << m)
    dp[0] = 0

    # we also store which row was used for a transition
    prev_row = [[-1] * (1 << m) for _ in range(n)]

    # To reconstruct properly, we store best choice per state
    choice = [[-1] * (1 << m) for _ in range(n)]

    for i in range(n):
        new_dp = dp[:]
        new_parent = parent[:]

        for mask in range(1 << m):
            if dp[mask] == INF:
                continue
            for j in range(m):
                if mask & (1 << j):
                    continue
                nxt = mask | (1 << j)
                val = dp[mask] + a[i][j]
                if val > new_dp[nxt]:
                    new_dp[nxt] = val
                    new_parent[nxt] = (mask, i, j)

        dp = new_dp
        parent = new_parent

    full = (1 << m) - 1
    print(dp[full])

    # reconstruct assignment
    used_rows = set()
    res = []

    mask = full
    while mask:
        pmask, i, j = parent[mask]
        res.append((i + 1, j + 1))
        used_rows.add(i)
        mask = pmask

    res.reverse()
    for i, j in res:
        print(i, j)

if __name__ == "__main__":
    solve()
```DP 数组存储每个列子集的最佳可实现总和。 关键细节是我们将每行 dp 复制到 new_dp 中，确保每行最多使用一次。 每次转换都会将当前行恰好分配给一列，从而保留唯一性。 

父指针存储每个状态的形成方式，从而可以通过从完整掩模向后走来进行重建。 每个存储的元组都会记住先前的掩码、行索引和使用的列索引。 

一个常见的陷阱是就地更新 dp，这将允许在单次迭代中多次使用同一行。 复制步骤通过在应用转换之前冻结先前的状态来防止这种情况发生。

 ## 边缘情况

 一个关键的边缘情况是当一行支配多列时。 例如：```
2 2
100 1
90 2
```贪婪的每列方法可能会在概念上将 row1 分配给两列，但 DP 确保 row1 被使用一次，强制正确分配 row1->col1 和 row2->col2 或反之亦然，具体取决于转换。 

另一个边缘情况是最佳解决方案需要牺牲局部最佳值以保持跨列的可组合性。 DP 自然地保留了这两种可能性，因为每个状态都独立地为每个子集保留最佳可实现的总和，而不是尽早致力于局部最优结构。
