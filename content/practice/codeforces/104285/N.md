 ## 解决方案
 ## 问题理解

 我们得到一个整数列表，并且允许我们将任何选定的元素重复增加一。 目标是转换数组，使所有值变得不同，同时执行尽可能少的增量。 

换言之，每个数字代表整数行上的起始位置。 我们只能向右移动点，并且每次移动都会花费一个单位的距离。 我们希望重新定位所有点，以便没有两个点落在同一整数上，从而最大限度地减少总移动。 

约束条件$n \le 2 \cdot 10^5$立即排除任何尝试为每次碰撞逐步模拟增量的方法。 即使每个元素只需要少量的移动，最坏的情况也可能涉及几乎整个数组的级联移动，如果处理不当，会导致二次行为。 

当许多值相同或紧密聚集时，就会出现微妙的失败情况。 例如，如果输入是$[5, 5, 5, 5]$，贪婪的“本地修复重复项”方法可能会分配诸如 5、6、7、8 之类的值，但粗心的实现总是增加当前重复项直到它变得唯一而不考虑早期的分配，可能会过度计数或错误处理排序。 另一个陷阱是以任意顺序而不是结构化顺序进行处理，这可能会破坏最优性，因为早期的决策会限制后来的决策。 

## 方法

 蛮力视图很简单：重复扫描数组，每当存在冲突时，增加其中一个重复项，直到它变得唯一。 这是可行的，因为每个增量操作都直接对允许的移动进行建模。 然而，每个增量都可能会触发与已处理的值的新冲突，因此在最坏的情况下，我们最终会在许多元素之间重复传播更改。 对于像所有相等值这样的输入，每个元素可以递增到$O(n)$次，给予$O(n^2)$行为。 

关键的结构观察是只有相对顺序才重要。 如果我们对数组进行排序，我们就消除了应该首先修复哪些值的所有歧义。 一旦排序，最优策略就变得贪婪和局部：每个数字只需要比之前选择的值至少大一。 这将全局碰撞问题转换为简单的线性扫描，我们在其中强制执行单调性。 

我们不再考虑任意增量，而是将任务重新解释为分配最终值$b_i$这样$b_i > b_{i-1}$和$b_i \ge a_i$，同时最小化$\sum (b_i - a_i)$。 排序确保任何最优解都可以重新排列成非降序，而不会增加成本。

 | --- | --- | --- | --- |
 | 暴力模拟|$O(n^2)$|$O(n)$| 太慢了|
 | 排序+贪婪扫描|$O(n \log n)$|$O(1)$或者$O(n)$| 已接受 |

 ## 算法演练

 我们按升序处理数组，这样早期的决策就不需要为后面的元素进行修改。 

1. 对数组进行非降序排序。 这确保我们首先处理小值，因此大值不会人为地阻止它们。 最佳结构必须遵循排序顺序，因为交换最终配置中的两个元素只能减少或保留所需的增量。 
2. 初始化变量`current`跟踪我们接下来可以分配的最小值。 这表示转换后的数组中最后选择的最终值。 
3. 迭代已排序的数组。 对于每个元素`x`，决定其最终值为`max(x, current)`。 这可确保该值至少与原始值一样大，并且在需要时严格大于先前选择的值。 
4. 通过添加来累计成本`final_value - x`到答案。 这直接计算有多少增量应用于该元素。 
5. 更新`current`到`final_value + 1`，强制下一个元素严格区分。 

每个步骤都会在本地执行最小的调整，同时保留全局可行性。 排序步骤确保当我们提高一个值时，我们以后不会遇到更小的原始值，从而需要重新审视之前的决策。 

### 为什么它有效

 核心不变量是，在按排序顺序处理第 i 个元素后，我们为前 i 个元素构造了尽可能小的严格递增序列，该序列尊重原始数组施加的所有下限。 任何最优解在按原值排序时都必须按升序赋值； 否则，交换两个相邻的无序分配不会增加成本并且会恢复顺序。 此交换参数保证贪婪地将每个值固定到最早的可用槽不会阻止以后的最佳解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    current = -10**18
    ans = 0

    for x in a:
        if x <= current:
            ans += current + 1 - x
            current = current + 1
        else:
            current = x
        # next must be strictly larger
        current += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现反映了贪婪的构造。 排序至关重要，因为它确保我们只需要与最后选择的值进行比较。 变量`current`代表下一个空闲整数槽。 当当前输入值已经足够大时，我们可以直接放置，无需额外成本。 否则，我们将其推进到`current`，支付差额。 

一个常见的微妙之处是更新`current`分配后。 它必须始终移动到`final_value + 1`，不仅仅是`final_value`，因为唯一性要求连续选择的值之间严格分离。 

## 工作示例

 考虑输入`[1, 1, 1]`。 

排序后，剩下`[1, 1, 1]`。 

| 元素| 当前之前 | 选择值| 成本增加 | 当前之后 |
 | --- | --- | --- | --- | --- |
 | 1 | -∞ | 1 | 0 | 2 |
 | 1 | 2 | 2 | 1 | 3 |
 | 1 | 3 | 3 | 2 | 4 |

 总成本为3。 

此跟踪显示如何将每个重复项推送到下一个可用整数，从而形成连续的链。 

现在考虑`[2, 2, 3]`。 

| 元素| 当前之前 | 选择值| 成本增加 | 当前之后 |
 | --- | --- | --- | --- | --- |
 | 2 | -∞ | 2 | 0 | 3 |
 | 2 | 3 | 3 | 1 | 4 |
 | 3 | 4 | 4 | 1 | 5 |

 第二个2必须增加，因为2已经被使用，并且3也必须向上移动以避免冲突。 

这些示例证实该算法始终按顺序分配最小的可行不同值。

 ## 边缘情况

 关键的边缘情况是所有元素都相同，例如`[5, 5, 5, 5]`。 排序后，算法分配 5、6、7、8，成本分别为 0、1、2、3。 这`current`指针确保每个新的分配都被推送到足以避免冲突的程度，而不是更多。 

另一个边缘情况是严格递增的数组，例如`[1, 2, 3, 4]`。 该算法分配的值保持不变，因为每个元素已经满足`current`约束。 这证实了贪婪规则永远不会引入不必要的增量。 

混合集群如`[1, 1, 2, 2, 3]`显示不同值之间的重复项如何相互作用。 该算法统一对待排序序列，并且`current`继承全局约束，以便在不破坏后续结构的情况下解决局部重复。
