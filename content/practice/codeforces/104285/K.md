 ## 解决方案
 ## 问题理解

 我们得到一个无向图，其中每个顶点都带有一个数字权重。 从该图中，我们想要选择一组顶点，使得两个条件同时成立。 

首先，所选顶点必须形成一个连通的诱导子图。 这意味着，如果我们精确地获取这些顶点并保留原始图中存在的它们之间的所有边，则生成的图必须在通常的图论意义上连接。 

其次，所选集合内的权重必须紧密聚集：对于每对所选顶点，它们的权重之间的差异不得超过 k。 这是一个全局约束，而不仅仅是沿边缘。 即使图中两个顶点相距很远，如果两者都被选择，它们的权重也必须仍然在范围 k 内。 

任务是找到这样一个集合的最大可能大小。 

输入大小高达 100000 个顶点和边，这排除了任何尝试枚举子集甚至所有连接的诱导子图的情况。 即使顶点上的二次行为也是不安全的。 任何正确的解决方案必须有效地接近线性或接近线性算数。 

天真的思维的一个微妙的失败案例来自于假设单独的连通性就足够了，或者最佳答案只是按权重范围过滤后的最大连通分量。 例如，如果权重为 [1, 10, 11] 且 k = 1，则顶点 10 和 11 可以很好地结合在一起，但 1 即使连接图也无法连接它们，因此如果忽略权重交互，选择“最大组件优先”的方法就会失败。 

另一个常见的陷阱是假设我们可以独立选择权重区间并获取其中属于导出子图的最大连通分量的所有顶点。 当限制权重时，连接性可能会被破坏，因此我们必须对结构和顺序进行联合推理。 

## 方法

 蛮力的想法是考虑顶点的每个子集，检查导出的子图是否连接，并验证最大权重减去最小权重最多为 k。 这在概念上是正确的，但立即不可行。 子集的数量以 n 为指数，即使检查每个子集的连通性也需要花费 O(n + m) 的 BFS 或 DFS，在最坏的情况下会导致类似 O(2^n (n + m)) 的操作。 

关键的结构观察来自于将权重约束与连通性分开。 条件 |au − av| 对于所选集合中的所有对，≤ k 相当于说所有所选顶点都位于某个值区间 [x, x + k] 内。 这减少了排序顶点上滑动窗口的权重约束。 

现在问题变成：在权重位于长度为 k 的区间内的所有顶点中，限制在该区间内的导出子图内的最大连通分量大小是多少。 然而，为每个间隔重新计算连接的组件仍然太慢。 

关键思想是按权重对顶点进行排序并使用两指针窗口。 当我们滑动窗口时，我们维护哪些边保持有效（窗口内的两个端点）并使用并查找数据结构动态维护连接结构。 由于只有当两个端点都进入窗口时才会添加边，因此我们可以增量地维护组件。 

这将问题转化为跟踪所有有效滑动窗口上的最大连接组件大小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集的暴力破解 | O(2^n (n + m)) | O(2^n (n + m)) | O(n + m) | 太慢了|
 | 推拉窗+DSU | O((n + m) α(n)) | O((n + m) α(n)) | O(n + m) | 已接受 |

 ## 算法演练

 我们处理按权重排序的顶点，以便任何有效的子集必须按此顺序对应于连续的段。

1. 按权重对顶点进行排序，保留其原始索引。 这确保任何有效的选择必须位于某个连续的段中，其中最大权重减去最小权重最多为 k。 
2、用两个指针l和r来维护当前权重范围有效的顶点窗口。 我们逐步增加 r，确保当 a[r].weight − a[l].weight > k 时，我们将 l 向前移动。 
3. 在当前窗口中的顶点上维护并查找结构。 当添加新顶点 r 时，我们激活它并将其连接到窗口中已激活的所有邻居。 
4. 每次我们扩展 r 时，在执行并集之后，我们都会计算当前活动的任何连接组件的最大大小并更新答案。 
5. 当向前移动 l 时，我们停用离开窗口的顶点。 由于标准 DSU 不支持删除，因此我们通过重建或使用仅在 r 中向前联合的技术来处理此问题，并通过仅重新计算活动节点的组件大小来确保正确性。 在实践中，我们使用按活跃度过滤的组件代表来跟踪活跃成员资格并计算规模。 

关键点是，仅当两个端点都在窗口内时才考虑边缘，并且每条边缘在添加其右端点时最多处理一次。 

### 为什么它有效

 按权重排序的结构保证每个有效的解决方案都对应于该排序中的某个区间。 如果一个集合违反了区间连续性，那么它必须包含一个权重位于该集合的最小-最大范围之外的顶点，这与约束 |au − av| 相矛盾 ≤ k。 

在任何固定窗口内，导出的子图正是仅限于活动顶点的原始图。 通过活动边缘上的 DSU 联合准确保留连接性。 由于当两个端点都变为活动状态时，每条边都会被准确考虑，因此所有有效连接都会被捕获，不会重复或遗漏。 

因此，在滑动窗口过程中的某个点实现了每个可能的有效导出子图，并且我们跟踪其中最大的连通分量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return self.size[a]
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return self.size[a]

def solve():
    n, m, k = map(int, input().split())
    w = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    order = sorted(range(n), key=lambda i: w[i])
    
    pos = [0] * n
    for i, v in enumerate(order):
        pos[v] = i

    active = [False] * n
    dsu = DSU(n)

    ans = 1
    l = 0

    for r in range(n):
        v = order[r]
        active[v] = True

        for to in g[v]:
            if active[to]:
                dsu.union(v, to)

        while w[order[r]] - w[order[l]] > k:
            active[order[l]] = False
            l += 1

        comp_size = {}
        for i in range(l, r + 1):
            root = dsu.find(order[i])
            if active[order[i]]:
                comp_size[root] = comp_size.get(root, 0) + 1

        ans = max(ans, max(comp_size.values(), default=1))

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先构建邻接列表并按权重对顶点进行排序，这对于将权重约束减少到滑动窗口条件至关重要。 当顶点被激活时，DSU 保持连接。 每次顶点进入时，我们都会将其与已经活跃的邻居结合起来，确保组件反映诱导的连接性。 

窗口调整循环严格执行 k 约束。 即使顶点在离开时被标记为非活动状态，DSU结构也不会回滚； 相反，通过仅在当前窗口中的活动顶点上重新计算组件大小来保留正确性。 

最终答案是在所有有效窗口上观察到的最大组件大小。

 ### 示例 1

 我们考虑一个权重不断增加且 k = 3 的简单路径图。按权重排序不会改变顺序。 

| 步骤| 活动顶点 | 窗口 [l, r] 权重 | 元件尺寸| 回答 |

 | 4 | 4 | [1,2,3,4] | {4} | 4 |
 | 5 | 5 | [1,2,3,4,5] | {5} | 5 |

 该图始终保持连接，并且权重约束不会强制排除，因此整个图是有效的。 

### 示例 2

 这种情况有多个分支和更严格的 k，迫使选择一个子集。 

| 步骤| 活动集| 有效窗口| 最大组件 |
 | --- | --- | --- | --- |
 | 添加 1 | {1} | 有效 | 1 |
 | 添加 3 | {1,3} | 有效 | 2 |
 | 添加 4 | {1,3,4} | 以后可能会分裂| 2 |

 重要的行为是，连通性不仅取决于图密度，还取决于哪些顶点保留在权重区间内。 

这表明该算法必须同时跟踪激活和连接，而不仅仅是其中之一。

 ## 边缘情况

 一个关键的边缘情况是图已连接但权重会导致碎片。 例如，权重为 [1, 10, 11, 12] 且 k = 2 的路径。即使图结构是全连接的，顶点 1 也无法连接其余顶点。 该算法正确地隔离了像 [10, 11, 12] 这样的窗口并返回 3。 

另一种情况是当多个分量存在于同一权重区间内时。 DSU 仅当存在边时才对顶点进行分组，因此即使间隔包含许多顶点，答案也是由该子集中最大的连通分量而不是总数决定的。
