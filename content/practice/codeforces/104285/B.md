 ## 解决方案
 ## 问题理解

 布莱恩走过一排摊位。 在每个摊位上，他都面临着一个选择：是将现金兑换成有限存储的代币，还是立即花费代币来获得吉祥物。 代币的行为就像一种可结转的受限资源，但它们的容量上限是固定的，因此任何多余的都会被丢弃。 

每个档位提供两个参数。 第一个是如果他在那里花钱，他会收到多少代币，第二个是他必须花费多少代币才能获得相同数量的吉祥物。 重要的是，购买代币不会直接影响吉祥物数量，购买吉祥物不会改变代币容量，只会减少当前代币库存。 

任务是在每个摊位决定采取两个动作中的哪一个，以便在按顺序处理所有摊位后最大化吉祥物的总数。 

这些约束立即排除了对决策的任何指数搜索。 对于多达 100,000 个摊位，任何将每个摊位分支为两个选择的方法都会增长 2^n，这是不可能的。 即使 O(n^2) 转换也会太慢。 唯一可行的解​​决方案是那些为每个仓位维持较小状态的解决方案，理想情况下与代币容量成正比。 

关键的结构约束是代币容量 m 最多为 100。这是决定性的暗示，任何有效的解决方案都必须将“当前持有的代币”视为动态编程状态维度。 

当代币购买超出上限时，就会出现微妙的边缘情况。 例如，如果 m = 10 并且您当前有 8 个代币，您购买了 5 个代币，那么您最终会得到 10 个，而不是 13 个。任何忘记限制这一点的实现都会错误地夸大未来的购买力。 

另一种边缘情况是当 bi 为零时。 在这种情况下，摊位可以用作免费吉祥物增益，不消耗代币，但仍然与代币购买选项竞争，这可能会更好，也可能不会更好，具体取决于未来的摊位。 此时贪婪的选择是不安全的。 

最后，ai = 0 的档位很重要。 它们允许免费获取代币，并且可以显着重塑未来的可行性，但前提是它们在正确的时间获取，因为它们仍然与吉祥物购买竞争。 

## 方法

 蛮力策略会模拟每一个可能的决策序列。 在每个摊位，我们都会分为两种可能性，要么购买代币，要么在有足够的代币可用时购买吉祥物。 这将构建一个每个节点有两个分支的决策树，从而导致 O(2^n) 状态。 除非我们认识到只有当前位置和当前令牌计数很重要，否则即使修剪相同的状态也是无效的。 

关键的观察是，做出未来决策所需的唯一记忆是布莱恩当前持有多少代币。 其他一切都由输入前缀固定。 由于令牌以 m 为界，因此每个摊位的不同状态总数最多为 m + 1。这将问题转换为在具有小状态空间的线上的动态规划。 

我们将状态 dp[i][t] 定义为在处理前 i 个档位并恰好持有 t 个令牌后可获得的吉祥物的最大数量。 从每个状态，我们考虑在 i 档的两个动作。 如果我们购买代币，我们就会过渡到 min(m, t + ai)。 如果我们购买吉祥物，我们会过渡到 t - bi，前提是 t ≥ bi，然后将 bi 添加到答案中。 

该结构实际​​上是一个分层图，其中每层只有 m 个节点，每个节点最多有两个传出转换。 这使得解为 O(nm)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 代币动态规划 | O(n·m) | O(米) | 已接受 |

 ## 算法演练

 我们逐一处理停顿，维护一个包含可能的令牌计数的 DP 表。

1. 初始化一个 DP 数组，其中 dp[t] 表示使用 t 个标记处理当前前缀后可实现的最大吉祥物。 最初 dp[0] = 0 并且所有其他状态都是不可能的。 
2. 对于每个档位 i，创建一个新的 next_dp 数组，其中填充不可能的值。 这种分离是必要的，以便来自同一档位的转换不会相互干扰。 
3. 对于从 0 到 m 的每个可能的令牌计数 t，如果 dp[t] 有效，则考虑两个操作。 
4. 首先考虑购买代币。 这会将状态移至 t + ai，但由于令牌有上限，我们将其限制为 m。 我们用 dp[t] 更新 next_dp[min(m, t + ai)]。 
5.其次考虑购买吉祥物。 如果 t ≥ bi，我们可以过渡到 t - bi 并将吉祥物数量增加 bi。 我们用 dp[t] + bi 更新 next_dp[t - bi]。 
6. 处理完停止 i 的所有令牌状态后，将 dp 替换为 next_dp。 
7. 处理完所有停顿后，答案是所有 dp[t] 中的最大值。 

这样做的原因是 dp[t] 始终表示处理每个前缀后给定令牌级别的最佳吉祥物计数。 每个有效的决策序列都准确地对应于通过这些状态的一条路径，并且每个状态转换准确地对应于停顿时的两个合法动作之一。 

不变的是，在处理 i 个停顿之后，dp[t] 存储以恰好 t 个令牌结尾的所有策略中可实现的最大吉祥物。 因为所有转换都在本地保留了正确性，并且我们详尽地考虑了这两种操作，所以不会排除任何最佳序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    NEG = -10**18
    dp = [NEG] * (m + 1)
    dp[0] = 0

    for i in range(n):
        ndp = [NEG] * (m + 1)

        ai = a[i]
        bi = b[i]

        for t in range(m + 1):
            if dp[t] == NEG:
                continue

            # option 1: buy tokens
            nt = t + ai
            if nt > m:
                nt = m
            if dp[t] > ndp[nt]:
                ndp[nt] = dp[t]

            # option 2: buy mascots
            if t >= bi:
                nt = t - bi
                val = dp[t] + bi
                if val > ndp[nt]:
                    ndp[nt] = val

        dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```该实现只保留两个数组，`dp`和`ndp`，以确保内存在 m 中保持线性。 哨兵值`NEG`代表无法到达的状态并防止无效转换的传播。 夹子`min(m, t + ai)`至关重要，因为超过代币上限不会创建额外的可用状态。 

每次迭代都严格使用前一个停顿中的值，这可以防止意外重用部分更新的状态。 

## 工作示例

 考虑一个小场景，其中 m = 5 并且存在三个停顿：

 在档位 1 处，假设 a1 = 2 且 b1 = 3。在档位 2 处，a2 = 3 且 b2 = 2。在档位 3 处，a3 = 0 且 b3 = 4。 

最初，dp 为：

 | 代币 | DP |
 | --- | --- |
 | 0 | 0 |
 | 1..5 | 1..5 -∞ |

 在第 1 个档位之后，从 0 个代币开始，我们可以购买代币达到 2 个代币，或者不做其他任何事情，因为我们无法购买吉祥物。 所以 dp 变为：

 | 代币 | DP |
 | --- | --- |
 | 0 | -∞ |
 | 2 | 0 |
 | 其他 | -∞ |

 在第 2 个档位之后，从状态 2 我们可以使用 5 个代币或花费 2 个代币购买 2 个吉祥物。 所以我们得到：

 | 代币 | DP |
 | --- | --- |
 | 0 | -∞ |
 | 3 | 0 |
 | 0 | 2（来自支出）|

 因此，现在最好的结构包括一个已经收集了吉祥物的分支，同时保持灵活性。 

在第 3 档之后，由于 a3 = 0，我们可以保持状态不变，或者如果可能的话，根据代币级别使用吉祥物。 这证明了零令牌转换仍然如何重塑最佳路径。 

该轨迹表明，最优性取决于延迟或提前代币支出决策，而不是尽可能贪婪地获取吉祥物。

 ## 边缘情况

 一个关键的边缘情况是当 ai 大到足以超过容量时。 例如，m = 5，ai = 10。从任何 t 开始，购买代币总是处于状态 5。算法正确地限制了这一点，确保不会出现超出容量的人为状态。 

另一种情况是当bi等于m时。 假设 m = 10 且 bi = 10。那么任何吉祥物购买都会完全耗尽代币，而后续的停滞在很大程度上取决于早期的代币积累是否值得。 DP 自然地捕获了这一点，因为转换允许移动到零令牌状态。 

当 ai = 0 且 bi = 0 时，两种操作都会保留令牌状态，但其中一种操作会提供免费的吉祥物。 DP 总是更喜欢积累这些免费吉祥物，因为 dp 转换保留最大值，并且不会发生无效的状态交互。 

最后，当所有 ai 为零时，系统就纯粹是一个何时花费代币的调度问题。 DP 减少为仅探索吉祥物消费路径，这仍然是正确处理的，因为状态永远不会增加，只会通过支出而减少。
