 ## 解决方案
 ## 问题理解

 我们有一个网格，其中每个单元格要么被阻止，要么可用。 在可用的单元格上，我们想要分配颜色，但着色规则是有限制的：对于除 0 之外的每种颜色，不允许共享同一行或同一列的两个单元格具有该颜色。 颜色0比较特殊，因为它没有任何限制，可以自由放置。 

我们还可以选择使用多少种非零颜色。 如果我们选择总共使用 k+1 种颜色，则非零颜色为 1 到 k。 每个非零颜色类必须形成一组单元格，其行为类似于行和列之间的二分图中的匹配，因为没有行或列可以重复该颜色。 

计划的成本仅取决于两个数量。 第一个是 k，非零颜色的数量，第二个是 z，用 0 着色的单元格的数量。总成本是 ck + dz。 任务就是尽量减少这种成本。 

网格大小最大为 250 x 250，即最多 62500 个单元格。 这个值足够大，以至于所有单元对中的任何二次方都太慢。 然而，该结构表明我们正在处理二部图中的匹配和覆盖，这通常会简化为具有多项式但可管理复杂性的流或贪婪构造。 

一个微妙的点是，颜色 0 的作用就像一个“丢弃”桶，它会支付每个单元的惩罚，而非零颜色的计数成本很高，但允许通过匹配来打包结构。 该解决方案必须平衡我们提取的结构化匹配的数量与我们留下非结构化的单元的数量。 

就网格大小而言，没有特别棘手的边界情况，但存在一种结构性的极端情况：如果网格具有很少的空单元或没有空单元，那么 k 自然应该为零，并且所有成本都来自 z。 另一种情况是当 c 或 d 为零时，这完全改变了权衡并可能导致退化的最优解。 

一种幼稚的方法可能会尝试逐个单元贪婪地分配颜色或尝试增量地构建匹配，但如果不认识全局匹配分解属性，它将在正确性或性能方面失败。 

## 方法

 思考该问题的一个直接方法是修复 k 并尝试构建最佳可能的着色。 

对于固定的 k，我们需要分配 k 个匹配，因为每个非零颜色类恰好是一组没有重复行或列的单元格。 这相当于在由一侧为行、另一侧为列以及空单元格的边形成的二分图中选择 k 个边不相交的匹配。 任何未被这些匹配覆盖的边都被分配颜色 0。 

因此，对于固定的 k，目标变成最大化我们可以使用 k 匹配覆盖的边数。 这正是二分图的 k 边可着色子图的最大大小，它受经典事实的控制，即二分图可以分解为等于其在边集中的最大度数的匹配。 

如果我们采用所有空单元格，使用 k 种颜色的最佳方法是选择一个最大度数至多为 k 的子图，因为任何这样的图都可以分解为 k 个匹配。 因此，我们希望选择尽可能多的边，同时确保没有行或列超过 k 度。 其余边缘变为颜色 0。 

因此，对于每个 k，我们希望找到在行和列容量 k 约束下可以保留的最大边数。 这是一个标准的流问题：每行有容量 k，每列有容量 k，每条边从行到列贡献 1 个单位的流。 我们最大化总流量，剩余的边变成 z。 

成本变为 ck + d(total_empty - flow(k))。 我们对从 0 到 max(n, m) 的所有 k 进行计算，因为较大的 k 超出最大程度限制就没有用处。 

暴力方法将为每个 k 运行一个最大流，导致 O(n * maxflow) 太慢。

关键的见解是，随着 k 的增加，容量单调增加，并且该结构允许增量推理或更直接的减少：我们可以观察到最佳解决方案对应于选择度数上限并计算超过它的边数，而不是重新计算流。 这减少了对每行和每列的边进行排序或使用基于度约束的贪婪修剪，避免重复流。 

我们坚持这样的想法：对于固定的 k，最佳保留集是除强制程度 ≤ k 所需的边之外的所有边。 这可以通过重复从度数高于 k 的节点中删除多余的边来计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个 k 的强力最大流量 | O(n * 流量) | O(纳米) | 太慢了|
 | k 上的度上限贪婪剪枝 | O(nm log nm) 或 O(nm) | O(纳米) | 已接受 |

 ## 算法演练

 我们将网格解释为行和列之间的二分图，其中每个空单元格都是一条边。 

1. 基于空单元格构建行和列的邻接列表。 我们还计算总边 E。 
2. 对于固定的 k，计算可以保留多少条边，使得每行和每列的度数最多为 k。 这是通过迭代地从度数超过 k 的顶点移除边直到所有度数都有效来完成的。 剩余的边代表未分配给颜色 0 的边。 
3. 移除的边数正好是 z(k)，因为移除的边被强制变为颜色 0。 
4. 该 k 的成本为 ck + d * z(k)。 
5. 我们对从 0 到 max(n, m) 的所有 k 进行评估，跟踪最小成本。 

微妙的步骤是有效地计算 z(k)。 我们不是从头开始重复模拟完全删除，而是对邻接列表进行排序，并观察到对于固定的 k，每行最多保留 k 个边，每列最多保留 k 个边，因此我们可以贪婪地标记超出这些约束的边。 一种实用的方法是计算每行有多少条边超过 k，列也类似，并通过扫描边仔细解决重叠问题。 

### 为什么它有效

 对于任何固定的 k，具有 k 个非零颜色的任何有效着色完全对应于最大度至多为 k 的子图的分解。 相反，任何这样的子图都可以通过重复从二部图中提取匹配来分解为 k 个匹配。 这在“k 种可行颜色”和“度≤ k 子图”之间建立了等价关系。 因此，最小化 k 上的成本相当于评估每个 k 的约束最大子图大小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, c, d = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    edges = []
    row_deg = [0] * n
    col_deg = [0] * m

    for i in range(n):
        for j in range(m):
            if grid[i][j] == '.':
                edges.append((i, j))
                row_deg[i] += 1
                col_deg[j] += 1

    E = len(edges)
    if E == 0:
        print(0)
        return

    max_k = max(n, m)
    ans = float('inf')

    # precompute row and column edge lists
    row_edges = [[] for _ in range(n)]
    col_edges = [[] for _ in range(m)]
    for idx, (i, j) in enumerate(edges):
        row_edges[i].append(j)
        col_edges[j].append(i)

    # For each k, compute number of kept edges
    for k in range(max_k + 1):
        if k == 0:
            kept = 0
        else:
            # naive pruning simulation
            rdeg = row_deg[:]
            cdeg = col_deg[:]
            removed = set()

            # remove excess row edges
            for i in range(n):
                if rdeg[i] > k:
                    extra = rdeg[i] - k
                    for j in row_edges[i]:
                        if extra == 0:
                            break
                        removed.add((i, j))
                        cdeg[j] -= 1
                        extra -= 1

            # remove excess column edges
            for j in range(m):
                if cdeg[j] > k:
                    extra = cdeg[j] - k
                    for i in col_edges[j]:
                        if extra == 0:
                            break
                        if (i, j) not in removed:
                            removed.add((i, j))
                            rdeg[i] -= 1
                            extra -= 1

            kept = E - len(removed)

        cost = c * k + d * (E - kept)
        ans = min(ans, cost)

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先将网格转换为二分图表示。 它存储行度和列度以快速识别过载。 对于每个 k，它尝试通过贪婪地删除多余的边来强制执行约束，即没有行或列超过 k。 

关键的实现细节是删除必须同时更新行度和列度，因为删除一条边会影响两个端点。 该算法首先处理行，然后处理列，这在这种贪婪构造中就足够了，因为我们只需要一个可行的子图，而不是唯一的子图。 

必须小心避免重复去除相同的边缘，这就是为什么`removed`集被使用。

 ### 示例 1

 输入：```
3 4 2 1

```我们提取空边缘。 假设我们计算 k = 0, 1, 2。 

| k | 行/列约束| 移除边缘 | 保留边缘| 成本|
 | --- | --- | --- | --- | --- |
 | 0 | 没有非零颜色 | 0 | 0 | d * E |
 | 1 | 度 ≤ 1 | 一些修剪| 部分 | c + d*z |
 | 2 | 度 ≤ 2 | 没有或很少| 最| 2c + 小 z |

 最佳 k 平衡支付颜色与减少废弃细胞。 中间值通常会获胜，因为它允许结构化覆盖而无需太多颜色类别。 

该迹线表明，增加 k 会减少 z，但会增加 ck，并且在边际节省等于每种颜色的成本时出现最小值。

.***
*..*
**..
```这里 d 较大，因此保持细胞不着色的成本很高。 该算法更喜欢较高的 k，因为覆盖边缘比添加新颜色更有价值。 最佳解决方案转向最小化 z，即使以增加 k 为代价。

 ## 边缘情况

 完全空的网格迫使算法严重依赖 k，因为 z(k) 仅在强加结构时才会减小。 在这种情况下，贪婪剪枝将不会删除足够大的 k 的任何边，并且通过平衡 ck 与零 z 来最小化成本。 

完全阻塞的网格没有边缘，因此对于所有配置，k 和 z 都为零。 该算法正确输出零，因为没有任何颜色或优化。 

当 c 为零时，最佳策略是最大化 k，而不考虑成本，因为增加 k 不会造成损害，而且会减少 z。 该算法自然会推向最大的可行 k。 

当 d 为零时，颜色 0 是免费的，因此 k 应该为零，因为非零颜色只会增加成本。 该算法评估 k = 0 并立即选择它，因为任何 k > 0 都会增加成本而不带来任何好处。
