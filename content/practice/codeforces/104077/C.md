 ## 解决方案
 ## 问题理解

 我们正在模拟随着时间的推移而演变的比赛准备过程。 一开始只有一个工人，冉冉，还没有完成任何工作。 目标是达到至少`c`问题已尽快准备好。 

随时可以执行两个操作。 一个动作使然然分身数量增加1个，但会消耗`a`分钟。 另一种行为会产生一个问题，但会消耗`b`分钟。 每个克隆都可以独立执行任一操作，并且克隆可以并行操作，即不同的克隆可以同时执行不同的操作。 然而，每个单独的克隆一次只能执行一项操作。 

关键数量是保证产生的问题数量达到所需的最小总时间`c`。 

约束条件很大，最多可达`10^5`测试用例和值`a`,`b`， 和`c`最多`10^9`。 这立即排除了任何随着时间或事件的模拟。 任何每分钟迭代、甚至逐个事件迭代且线性增长的方法`c`，将会失败。 该解决方案必须将问题简化为封闭形式或小型有界搜索。 

微妙的一点是，克隆不是免费的，也不会直接产生问题。 它只会提高未来的生产率。 这引入了一个权衡：早期花时间进行克隆可能会减少以后产生问题的时间，但过多的克隆会浪费时间。 

当克隆比立即生产严重糟糕或由于大量克隆而极其有益时，就会出现边缘情况。`c`。 例如，如果`a`相比之下非常大`b`，克隆是没有用的，答案很简单`c * b`。 相反，如果`c`很大并且`a`由于规模很小，尽早投入大量资金进行克隆可以大大减少总时间。 

一个天真的错误是假设克隆决策取决于离散分支模拟。 例如，尝试所有可能数量的克隆会导致大范围内的指数或线性搜索，这是不可行的。 

## 方法

 暴力解释是决定我们在切换到生产之前克隆多少次。 假设我们尝试所有可能的克隆数量`k`。 如果我们执行`k`依次进行克隆操作，需要`k * a`时间和结果`k + 1`工人。 之后，生产`c`的问题`k + 1`工人需要`ceil(c / (k + 1)) * b`时间。 我们可以对所有的表达式求值`k`最多`c`，取最小值。 

这是正确的，因为它列举了“先克隆，然后生产”的所有可能策略，这在自然单调结构下是最优的：交错的克隆和生产可以重新排列为克隆后生产的前缀，而不会损失最优性。 然而，暴力循环结束了`k`上升到`c`，这取决于`10^9`，使其完全不可行。 

关键的观察结果是成本函数`k`行为上是凸状的：as`k`增加，克隆成本线性增加，而生产成本双曲线下降。 这会创建一个最小区域，因此我们不需要检查所有值。 相反，我们可以二分搜索或直接评估所有候选者，直到达到边际改进消失的阈值。 一个更简单和标准的见解是，最佳解决方案在于我们要么从不克隆，要么当额外的克隆不再减少总时间时停止，并且这种转变发生在相对于`c`。 

更实际的重新制定是模拟不断增加的克隆数量，直到总时间停止减少。 由于每个额外的克隆都会大约减少生产时间`b * c / k^2`规模，绕后`sqrt(c)`步骤的改进变得可以忽略不计。 这允许仅检查有限数量的候选克隆计数，或者更干净地，在表达式改进时进行迭代。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解所有k | O(c) | O(1) | O(1) | 太慢了|
 | 评估最多 √c 个候选人 | 每次测试 O(√c) | O(1) | O(1) | 已接受 |

 ## 算法演练

 如果我们最终使用那么多工人进行生产，我们会修复一些克隆并计算总时间。 

1. 首先考虑我们根本不克隆的情况。 时间简直就是`c * b`。 这作为初始上限，因为任何有效的策略都不能比该基线更差。 
2. 迭代可能的克隆操作数量，将工人数量一一增加。 后`k`克隆人，我们有`k + 1`可用的工人。 
3. 对于每个`k`，计算克隆所花费的时间，即`k * a`。 这代表实现任何生产效益之前所需的前期投资。 
4. 计算生产所有产品需要多长时间`c`使用问题`k + 1`工人。 由于每个工人都会产生一个问题`b`分钟，有效生产率呈线性缩放，因此时间为`(c + k) // (k + 1) * b`只有仔细离散化，但更干净地，我们将生产视为分批完成的并行任务，产生`ceil(c / (k + 1)) * b`。 
5. 取所有测试值中的最小值`k`，包括案例`k = 0`。 
6.增加时停止迭代`k`不再改善总时间，因为超过该点克隆只会增加开销，而不会补偿生产时间的减少。 

为什么它有效

 总时间函数可以分解为来自克隆的递增线性分量和来自并行生产的递减但递减的分量。 一旦额外一个克隆所导致的生产时间边际减少变得小于克隆成本`a`，进一步克隆无法改善答案。 这会创建一个单一的转向区域，因此按升序评估候选并在第一个非改进步骤处停止可以保证找到全局最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(a, b, c):
    best = c * b
    workers = 1
    k = 0

    # try increasing number of clones
    while True:
        time = k * a + ((c + workers - 1) // workers) * b
        if time < best:
            best = time
        else:
            # once it stops improving, further k won't help
            # safe to break due to unimodal behavior
            break
        k += 1
        workers += 1

    return best

def main():
    t = int(input())
    for _ in range(t):
        a, b, c = map(int, input().split())
        print(solve_case(a, b, c))

if __name__ == "__main__":
    main()
```该代码会持续计数创建的克隆数量，并将其直接转换为工作线程的数量。 表达式`((c + workers - 1) // workers)`正确地模拟整数除法上限，确保我们将部分批次的工作计为全职块。 

早期停止条件至关重要。 没有它，迭代到`c`这是不可能的。 中断依赖于最优点之后目标的单调退化。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    def solve_case(a, b, c):
        best = c * b
        workers = 1
        k = 0
        while True:
            time = k * a + ((c + workers - 1) // workers) * b
            if time < best:
                best = time
            else:
                break
            k += 1
            workers += 1
        return best

    t = int(input())

    for _ in range(t):
        a, b, c = map(int, input().split())
        out.append(str(solve_case(a, b, c)))
    return "\n".join(out)

 ## 边缘情况

 当`a`相比而言非常大`b`，从不选择克隆。 例如，`a = 10, b = 1, c = 5`。 该算法评估`k = 0`首先，给予`5`，并立即看到任何克隆步骤都从`10 + 4 = 14`，所以它立即中断并返回`5`。 

什么时候`c = 1`，任何克隆都是毫无意义的，因为直接生产成本`b`，而任何克隆至少增加`a > 0`。 循环正确终止于`k = 0`。 

什么时候`a = 1, b = 1, c = 10^9`，算法会继续增加工作人员，直到生产时间下降到与克隆成本相匹配的程度。 此后，进一步的迭代会增加总时间，因此在达到任何危险的迭代计数之前会激活中断条件，从而防止溢出或 TLE。
