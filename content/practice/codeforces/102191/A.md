 ## 解决方案
 ## 问题理解

 我们从`n`糖果，并希望向尽可能多的不同朋友赠送糖果，每个朋友一颗糖果。 每两个朋友收到一颗糖果后，如果还有剩余的糖果，我们就会自己吃一颗糖果。 这个过程一直持续到我们不能再给朋友另一颗糖果为止。 

任务是计算可以收到糖果的最大好友数量。 

的价值`n`可以大到`10^9`。 这立即排除了对每个糖果执行一次操作的任何模拟，因为在最坏的情况下它将执行大约十亿次迭代。 即使每次迭代的工作量很小，也远远超出了亚秒级竞争性编程解决方案所能承受的范围。 我们需要直接从流程的结构中得出答案。 

最微妙的情况发生在没有糖果可吃的时候。 例如，使用输入`2`，答案是`2`， 不是`1`。 我们给两个朋友每人一颗糖果，然后我们就没有东西可以吃了，所以两个朋友都吃完了。 如果一个粗心的公式总是在每一对之后减去一颗糖果，那么就会错误地拒绝第二个朋友。 

另一个边界情况是`4`。 正确答案是`3`。 我们给前两个朋友糖果，吃掉一颗糖果，剩下一颗糖果给第三个朋友。 之后，该过程停止。 如果天真的计算为每两个朋友吃一颗糖果，可能会错误地期望为三个朋友提供超过四颗糖果。 

输入`6`是另一个有用的边界情况。 答案是`4`， 不是`5`。 招待了两个朋友后，吃掉一颗糖，剩下三颗。 然后我们又招待了两个朋友，留下一个，最后一颗糖果就被吃掉了。 第五个朋友已经一无所有了。 这捕获了将所有剩余糖果自动提供给朋友的公式。 

## 方法

 直接的暴力解决方案可以模拟实际过程。 保持糖果的数量，反复给一个新朋友一颗糖果，并且在每两个朋友之后尽可能吃一颗糖果。 模拟是正确的，因为它完全遵循过程规则。 然而，它可以执行 θ(`n`）迭代。 和`n = 10^9`，这意味着最多十亿次迭代，这对于时间限制来说太慢了。 

有用的观察结果是该过程具有简单的重复模式。 考虑三颗糖果。 他们可以产生两个朋友：两个糖果给两个朋友，第三个糖果被吃掉。 因此，每三个糖果组成的完整组实际上贡献了两个朋友。 完成这些组后剩下的糖果都可以送给其他朋友，因为他们的数量少于三个，并且他们无法强制另一个完整的饮食周期。 

让`n = 3q + r`， 在哪里`r`是`0`,`1`， 或者`2`。 

这`q`完整的三组糖果会导致`q`糖果可以吃掉，剩下的`r`糖果送给朋友。 因此好友数量为`n - q = n - floor(n / 3)`。 

从相反的方向也可以得到同样的结果。 服务`k`朋友们，这个过程需要`k`给朋友的糖果加上每对之后有一个朋友吃过的糖果，然后是另一个朋友。 这使得每消耗三颗糖果，两颗有用糖果的比例相同，最后的不完整组直接由剩余的糖果处理。 

因此，整个模拟分解为一次整数除法和一次减法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 | O(n) | O(1) | O(1) | 太慢了|
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取糖果的数量`n`。 唯一需要的信息是总数，因为该过程不区分糖果或朋友。 

2. 计算`n // 3`。 这是三颗糖果的完整组数。 每个这样的组包含一颗糖果，必须吃掉它而不是送给朋友。 

3. 减去该数字`n`。 结果，`n - n // 3`，是最终可以送给朋友的糖果数量。 

4. 打印结果。 

为什么即使最后一组有一两颗糖果，三人分组仍然有效？ 一个完整的小组包括一颗被吃掉的糖果和两颗送给朋友的糖果。 在完成整个进食周期后，剩下的一两颗糖果可以直接送给朋友，因此不需要额外扣除。 

### 为什么它有效

 关键的不变量是，每消耗三颗完整的糖果，好友可用的糖果数量就会减少一粒。 这样的块中的两颗糖果被送给朋友，同时一颗被吃掉。 如果`n = 3q + r`，正好有`q`完整的块和`r < 3`剩下的糖果。 完整的块正好占`q`吃了糖果，而所有`r`剩菜可以送给朋友。 因此确切地说`q = floor(n / 3)`糖果因吃而消失，好友数量上限为`n - floor(n / 3)`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
print(n - n // 3)
```输入是一个整数，因此程序直接将其读取为`n`。 Python 整数很容易处理`10^9`，尽管这里即使是 32 位有符号整数也足够了。 

表达式`n // 3`执行整数除法并给出完整的三组数。 从中减去它`n`给出到达朋友手中的糖果数量。 

没有循环，因此没有需要管理的模拟边界或逐一转换。 特别是，使用整数除法可以正确处理诸如`2`,`4`， 和`5`：它们的商除以三是`0`,`1`， 和`1`， 分别。 

## 工作示例

 ### 示例 1

 对于`n = 4`，整数除法给出`4 // 3 = 1`。 吃掉一颗糖果，剩下三颗糖果可以送给朋友。 

|`n`|`n // 3`| 朋友们`n - n // 3`|
 |---:|---:|---:|
 | 4 | 1 | 3 |

 相应的过程是给两个朋友糖果，吃掉一颗糖果，然后把剩下的糖果给第三个朋友。 输出是`3`。 

### 示例 2

 对于`n = 5`，仍然只有一组完整的三颗糖，因此吃掉了一颗糖果。 另外四颗糖果送给了朋友。 

|`n`|`n // 3`| 朋友们`n - n // 3`|
 |---:|---:|---:|
 | 5 | 1 | 4 |

 该过程可以为四个朋友提供服务：两个朋友收到糖果，一个糖果被吃掉，剩下的两个糖果送给另外两个朋友。 输出是`4`。 

这些例子也说明了为什么其余部分很重要。 从五颗糖果中取出一组完整的三颗糖果后，剩下两颗糖果，并且都可以赠送出去，而不会产生另一个饮食循环。

import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())

 ## 边缘情况

 对于`n = 1`，算法计算`1 // 3 = 0`，所以答案是`1`。 只有一颗糖果，直接送给一位朋友。 不会触发进食周期。 

为了`n = 2`，算法计算`2 // 3 = 0`，给出答案`2`。 我们可以招待两个朋友，第二颗糖果吃完后就没有糖果可吃了。 这是打破每对糖果后盲目移除一颗糖果的实现的边界。 

为了`n = 4`，算法计算`4 // 3 = 1`, 给予`4 - 1 = 3`。 实际的顺序是给予两颗糖果，一颗被吃掉，最后一颗糖果给第三位朋友。 三个完整的一组就占了吃掉的一颗糖果。 

为了`n = 6`，算法计算`6 // 3 = 2`, 给予`6 - 2 = 4`。 前两个朋友消耗了两颗糖果并触发一颗被吃掉的糖果。 接下来的两个朋友又吃了两颗糖果，并触发第二颗吃掉的糖果。 剩余的糖果无法支持第五个朋友，因此最多四个。 

为了`n = 10^9`，该算法执行与任何较小输入完全相同的恒定工作量。 自从`10^9 // 3 = 333333333`，答案是`1000000000 - 333333333 = 666666667`。 这证实了该解决方案不依赖于`n`通过迭代计数。
