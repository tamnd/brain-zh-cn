 ## 解决方案
 ## 问题理解

 我们从`n`糖果，并想给尽可能多的不同的朋友送糖果。 给一个朋友一颗糖果很简单，但是每给朋友一颗糖果，如果剩下一颗糖果，我们就会自己吃掉一颗糖果。 问题是，当我们选择最佳的给予糖果的顺序时，最终能有多少糖果到达朋友手中。 

输入包含单个整数`n`，代表初始糖果数量。 输出是每人可以收到一颗糖果的最大好友数量。 

上限`n <= 10^9`排除任何对每种糖果执行一个或多个操作的方法。 线性模拟需要多达十亿次迭代，这远远超出了竞争性编程时间限制所能容忍的范围，尤其是在规定的有效零秒限制的情况下。 我们需要识别重复结构并在常数时间内直接计算答案。 内存要求很小，因为只需要单个输入值和答案。 

最小的输入暴露了边界行为。 为了`n = 1`，正确答案是`1`，因为唯一的糖果可以被赠送，并且没有第二个糖果可以触发进食。 总是为每三块一组减去一颗糖果的公式仍然必须正确处理这种情况。 

为了`n = 2`，答案是`2`。 我们可以把两颗糖果都送给两个朋友，然后我们才需要吃一颗糖果，但没有剩下。 如果粗心地假设每对礼物总是花费额外的糖果，那么就会错误地返回`1`。 

三的倍数是另一个有用的边界。 和`n = 6`，我们可以给两颗糖果，吃一颗，然后再给两颗糖果，吃最后一颗。 答案是`4`， 不是`3`。 吃东西发生在每对礼物之后，因此最终消耗的糖果并不对应于失去了一个额外的朋友。 

## 方法

 直接模拟可以一次模拟一颗糖果的过程。 我们保留剩余糖果的数量以及收到糖果的朋友数量。 每当我们有足够的糖果可以赠送另一颗糖果时，我们就会把它送给朋友。 如果可能的话，每送完第二份礼物，我们就会吃掉一颗糖果。 这个模拟是正确的，因为它完全遵循问题所描述的过程，并且尽可能选择赠送糖果是最佳的，因为目标只是最大化礼物的数量。 

问题在于迭代次数。 在最坏的情况下，模拟执行 θ(n) 功，这意味着最多大约`10^9`迭代。 那太慢了。 

关键的观察结果是，每组完整的三颗原始糖果恰好会产生两份礼物。 给朋友两颗糖果，第二颗礼物后一颗糖果被吃掉。 当至少剩下三颗糖果时，相同的图案可以独立重复。 这意味着我们不需要模拟单个糖果。 我们可以计算出有多少个完整的三组糖果，并分别处理最后的一两颗糖果。 

如果`n = 3q + r`，那么`q`完整的团体贡献`2q`朋友们。 如果`r = 0`，什么都没有剩下。 如果`r = 1`，剩余的糖果可以再送给一位朋友。 如果`r = 2`，剩下的两颗糖果都可以送出，因为吃规则只适用于第二颗礼物之后，并且之后就没有剩余的糖果了。 

这给出了紧凑的公式`answer = n - floor(n / 3)`。 

从群体解释中也可以得到同样的结果。 每三颗糖果就会导致两颗糖果到达朋友手中，因此每组中恰好有一颗糖果因吃而丢失。

 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取糖果的数量`n`。 只需要这个值，因为该过程完全取决于剩余的糖果数量。 
2. 计算`n // 3`，三颗糖果的完整组数。 每个这样的小组需要花费一颗糖果来吃饭，并允许将两颗糖果送给朋友。 
3、原来的糖果数量减去吃掉的糖果数量。 结果值，`n - n // 3`，是可以到达好友手中的最大糖果数量。 
4. 打印结果。 不需要模拟或附加状态。 

### 为什么它有效

 考虑每块完整的三块糖果。 我们可以将其中两份送给两个朋友，在第二份礼物之后我们吃第三份。 因此，三颗糖果恰好可以产生两份成功的礼物。 处理完所有完整的方块后，最多剩下两颗糖果。 显然可以赠送一颗剩余的糖果，并且可以同时赠送剩余的两颗糖果，因为吃动作仅发生在第二份礼物之后，当没有剩余的糖果可供食用时。 因此，唯一无法到达朋友手中的糖果正是`floor(n / 3)`糖果，每组三颗糖果。 答案是`n - floor(n / 3)`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    print(n - n // 3)

if __name__ == "__main__":
    solve()
```这`solve`函数读取输入格式指定的单个整数。 不需要循环，因为问题只包含一个测试用例。 

表达式`n // 3`计算可以出现多少个完整的三颗糖果组。 从中减去这个`n`直接统计没有消耗掉的糖果。 剩下的糖果与能收到糖果的好友一一对应。 

Python 整数处理的值远大于`10^9`，因此整数溢出不是问题。 整数除法也是特意进行的取整除法。 使用普通除法会产生浮点值，并且不能正确表示完整组的数量。 

不存在逐一调整。 例如，`n = 2`给出`2 - 0 = 2`， 尽管`n = 3`给出`3 - 1 = 2`。 这些情况之间的过渡正是第一颗自吃糖果出现的地方。

 ## 边缘情况

 对于`n = 1`，算法计算`1 // 3 = 0`，所以答案是`1 - 0 = 1`。 唯一的糖果送给了一位朋友，没有第二件礼物可以让我们吃任何东西。 

为了`n = 2`，计算为`2 // 3 = 0`, 生产`2 - 0 = 2`。 两种糖果都可以分发。 这解决了一个常见的错误，即每当两个朋友收到糖果时就减去一颗糖果，而不检查糖果是否还有待吃。 

为了`n = 3`，计算变为`3 // 3 = 1`, 给予`3 - 1 = 2`。 两颗糖果送给朋友，第三颗是在第二颗礼物之后吃掉的。 这是实际发生自消耗的最小输入。 

为了`n = 6`，有两个完整的三组。 公式给出`6 - 2 = 4`。 从操作上来说，前两份礼物会消耗一颗额外的糖果，接下来的两份礼物会消耗最后的糖果，因此四个朋友会收到糖果。 

为了`n = 8`， 有`8 // 3 = 2`完成小组，留下两颗糖果。 完整的两组提供四份礼物，最后两颗糖果又提供两份，总共六份。 公式给出`8 - 2 = 6`，确认剩余的两个被处理而没有额外的惩罚。
