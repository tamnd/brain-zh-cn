 ## 解决方案
 ## 问题理解

 move 字符串描述了从某个初始单元格开始在无限整数网格上行走。 每个字符都会在四个基本方向之一上将当前单元格更改一个单位。 我们需要移动字符串的最长连续部分，其相应的行走永远不会两次占用同一个单元格。 

所选子字符串的起始单元格算作已访问的单元格。 这个细节很重要，因为像这样的子字符串`RL`首先向右移动，然后立即返回到其起始单元格，因此它是无效的。 

表示行走的一种有用方法是使用前缀位置。 令 P i ​ 为第一个 i 次移动后到达的单元格，其中 P 0 ​ 为起始单元格。 从 move l 到 move r 的子串恰好访问了这些位置

 P l−1 ​ ,P l ​ ,…,P r ​ 。 

因此，当这些前缀位置全部不同时，子字符串准确有效。 原来的移动问题现在已经变成了一个熟悉的数组问题：找到不包含重复值的前缀位置的最长连续范围。 

长度可以达到 10 6。在最坏的情况下，O(n 2 ) 算法已经需要大约 5⋅10 11 次迭代，远远超出了 1.5 秒的时间限制所允许的范围。 我们需要一种线性时间或接近线性时间的方法。 256 MB 的内存限制还意味着，不小心存储大量 Python 对象可能会变得相关，因此实现应该使用紧凑的坐标表示，而不是存储坐标元组。 

有几种边缘情况很容易导致错误的答案。 为了`R`，唯一访问的单元格是起始单元格和紧邻其右侧的单元格，所以答案是`1`。```
1R
```正确的输出是`1`。 一个粗心的实现，计算访问过的单元而不是移动可能会输出`2`，而所需的答案是移动次数。 

为了`RL`，蛇返回到其起始单元格。```
2RL
```正确的输出是`1`。 仅检查连续移动是否不同的方法会错误地接受整个字符串。 重复的单元格可以通过多次移动来分隔，因此我们必须跟踪位置而不仅仅是方向。 

为了`RULD`，最后一步返回到初始单元格。```
4RULD
```正确的输出是`3`。 完整的步行包含两次起始位置，但前三个动作构成有效的步行。 该算法必须缩小当前窗口，而不是丢弃之前看到的所有内容。 

另一个微妙的情况是先前出现的位置已经在当前窗口之外。 例如，考虑`RRLR`。 前缀位置为 0,1,2,1,2。 当第二个`1`出现时，有效窗口必须移过旧窗口`1`。 后来，当`2`重复，只有当前窗口重要。 一个常见的滑动窗口错误是将左边界直接分配给`last[position] + 1`，这可以向后移动边界。 边界只能向前移动。 

## 方法

 直接的方法是选择每一个可能的起始位置并一次移动一步来扩展子串。 在扩展时，我们维护当前坐标和一组已访问过的单元格。 如果下一个单元格已在集合中，则无法再扩展子字符串。 否则我们插入它并更新答案。 这是正确的，因为对于每个起始位置，我们明确地找到从那里开始的后缀的最长有效前缀。 

问题在于重复工作量。 在输入如`RRRR...R`，每个起始位置都会生成一个有效的子字符串，一直到末尾。 该算法检查

 n+(n−1)+⋯+1= 2 n(n+1) ​

 扩展，n=10 6 时为 500000500000。即使在考虑集合运算之前，这也已经太大了。 

蛮力之所以有效，是因为它独立地维护每个起点的单元集，但只要起点发生变化，它就会丢弃信息。 关键的观察结果是所有子字符串都对应于同一前缀位置数组的连续范围。 如果我们维护一个没有重复项的前缀位置窗口，那么当出现重复项时，我们只需将左边界移动足够远即可删除该位置的上一个出现位置。 

假设当前前缀位置 P i 最后一次出现在索引 j 处。 如果当前有效窗口从 L 开始，则当 j≥L 时恰好发生重复。 新窗口必须在 j 之后开始，所以我们设置

 L=max(L,j+1)。 

如果 j<L，则旧事件已经在当前窗口之外，不需要更改。 每个前缀位置处理一次，左边界仅向前移动，给出 O(n) 解。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n 2 ) | O(n) | 太慢了 |
 | 最佳 | O(n) 预期 | O(n) | 已接受 |

 ## 算法演练

 1. 将起始单元格表示为前缀位置 P 0 ​ =(0,0)。 对于每次移动，更新当前坐标以获得下一个前缀位置。 
2. 维护一个前缀索引[L,i]的滑动窗口，其位置都不同。 相应的移动子串的长度为 i−L，因为它由移动 L+1,…,i 组成。 
3. 存储每个坐标被访问的最新前缀索引。 当 P i 生成时，查找其先前的索引 j。 
4. 如果j≥L，则当前位置出现在窗口内部，因此该窗口不再有效。 将其左边界移至 j+1。 我们使用`max`因为左边界永远不允许向后移动。 
5. 记录`i`作为当前位置的最新出现。 这必须在确定新边界之后发生，因为未来的发生需要知道当前索引。 
6. 当前窗口包含`i-L+1`不同的前缀位置，对应于`i-L`移动。 更新答案`i-L`。 

为什么它有效：在每次迭代中，不变的是从 P L ​到 P i ​的所有前缀位置都是不同的。 如果新位置在此窗口内之前没有出现过，则不变量保持为真。 如果它确实在 j 处出现，则每个以 i 结束的有效窗口必须在 j 之后开始，因此将 L 移动到 j+1 是必要且充分的。 由于以 i 结尾的每个有效子字符串都必须由以 i 结尾的无重复窗口表示，因此最大的此类窗口给出了该端点的最佳答案。 取所有端点的最大值从而给出全局最长的有效子串。 

## Python 解决方案```python
Pythonimport sysinput = sys.stdin.readline

def solve(s):    n = len(s)
    # Encode (x, y) into one integer so that the dictionary    # stores only integer keys instead of coordinate tuples.    base = 2 * n + 3    offset = n + 1
    x = 0    y = 0
    # last[position] = latest prefix index containing this position.    last = {offset * base + offset: 0}
    left = 0    ans = 0
    for i, ch in enumerate(s, 1):        if ch == 'R':            x += 1        elif ch == 'L':            x -= 1        elif ch == 'U':            y += 1        else:            y -= 1
        key = (x + offset) * base + (y + offset)
        previous = last.get(key)        if previous is not None and previous >= left:            left = previous + 1
```这`solve`函数处理动作的方式与演练中完全相同。`x`和`y`存储当前前缀位置，同时`i`是它的前缀索引。 

坐标位于 -n 和 n 之间，因为只有 n 次移动。 表达式```
Pythonkey = (x + offset) * base + (y + offset)
```将每个可能的坐标对映射到唯一的整数。 使用一个整数作为字典键比为每个访问的单元使用一个二元素元组要节省得多的内存，这在 n 大到 10 6 时很重要。 

初始位置必须插入索引`0`。 如果没有它，将无法检测到返回其起始单元的路径。 这就是为什么`RL`一定有答案`1`而不是`2`。 

条件`previous >= left`是另一个重要的边界检查。 当前窗口之前的先前出现不会使当前窗口无效。 写作`left = previous + 1`无条件地会错误地向后移动窗口。 

答案是`i - left`， 不是`i - left + 1`。 该窗口包含前缀位置 L 到 i，但移动次数比位置少一次。 Python 整数不会溢出，因此坐标编码或答案不需要特殊处理。

Pythonimport sysimport io

def solve(s):    n = len(s)    base = 2 * n + 3    offset = n + 1
    x = 0    y = 0
    last = {offset * base + offset: 0}
    left = 0    ans = 0
    for i, ch in enumerate(s, 1):        if ch == 'R':            x += 1        elif ch == 'L':            x -= 1        elif ch == 'U':            y += 1        else:            y -= 1

 ## 边缘情况

 对于最小输入`1 / R`，算法从前缀位置开始`(0,0)`。 后`R`，达到`(1,0)`，以前没有出现过。 窗户是`[0,1]`，包含两个不同的位置，因此包含一个动作。 输出是`1`。 

为了`RL`，前缀位置是`(0,0)`,`(1,0)`， 和`(0,0)`。 当最终位置生成时，它的前一个索引是`0`，它位于当前窗口内，从`0`。 算法改变`left`到`1`，保留前缀位置`1`和`2`。 这代表单个有效的移动`L`，所以输出是`1`。 

为了`RULD`，第四步到达`(0,0)`，其上一次出现在索引处`0`。 左边界从`0`到`1`，留下有效的三步子串`ULD`。 答案已经是`3`，因此重复的起始单元不会导致算法丢失最佳的较早子串。 

为了`RRLR`，前缀位置是`(0,0)`,`(1,0)`,`(2,0)`,`(1,0)`,`(2,0)`。 在索引处`3`,`(1,0)`最后出现在索引`1`， 所以`left`变成`2`。 在索引处`4`,`(2,0)`最后出现在索引`2`，这正是当前的左边界，所以`left`变成`3`。 最大的窗口有长度`2`，对应于前两个动作`RR`，输出是`2`。 这个案例专门检查了`left`仅在必要时进行推进。 

对于由一百万组成的最大尺寸输入`R`字符，每个前缀位置都不同，因为每次移动后 x 坐标都会增加 1。 没有发现重复项，所以`left`遗迹`0`答案逐渐变成`1000000`。 该算法对每个字符执行一次迭代，证明了为什么 O(n) 方法可以处理上限，而二次方法却不能。
