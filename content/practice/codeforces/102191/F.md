 ## 解决方案
 ## 问题理解

 我们需要将数组切割成连续的子数组。 每个子数组将其元素和作为一个因子，目标是最大化所有这些因子的乘积。 输出是原始数组`/`插入连续部分之间。 

关键的困难在于乘积可能会变得非常大，因此任务并不是要求我们计算最大乘积。 我们只需要恢复一个分区即可实现这一目的。 约束最多允许 (3\cdot10^5) 个元素，因此 (O(n)) 或 (O(n\log n)) 解决方案是合适的。 任何指数都是不可能的，即使是 (O(n^2)) 动态程序在最坏的情况下也需要大约 (9\cdot10^{10}) 次迭代。 

事实上，每个数组值都是正数，这使得问题崩溃为简单的贪婪构造。 当部分的总和为 (1) 时，粗心的实现可能会失败。 例如，对于```
2
3 1
```正确的输出是```
3 1
```因为分区`[3] / [1]`有产品 (3)，而`[3 1]`有产品 (4)。 当当前总和至少达到 (2) 时进行切割，然后盲目打印最终单例的策略将产生无效的次优分区`[3] / [1]`。 

另一种边界情况是完全由 1 组成的数组。 为了```
3
1 1 1
```正确的输出是```
1 1 1
```而不是`[1 1] / [1]`。 后者有乘积(2)，而单个部分有和(3)和乘积(3)。 最后剩下的部分必须与前一部分合并。 

单元素数组也需要明确考虑。 为了```
1
1
```没有可以与元素合并的相邻部分，因此唯一可能的答案就是`1`。 

## 方法

 暴力解决方案可以枚举每组可能的切割。 相邻元素之间有 (n-1) 个间隙，每个间隙可以包含切割，也可以不包含切割，从而精确地给出 (2^{n-1}) 个分区。 对于每个分区，我们可以计算所有部分的总和及其乘积，然后保留最佳分区。 即使产品是增量维护的，这仍然需要 (2^{n-1}) 次分区评估。 如果通过扫描整个数组来评估每个分区，则成本变为 (O(n2^n))。 在 (n=3\cdot10^5) 处，甚至 (2^{n-1}) 本身也超出了任何实际限制。 

消除指数搜索的观察结果是不等式

 [
 xy \ge x+y
 ]

 每当 (x,y\ge2) 时。 考虑两个相邻部分，其总和为 (x) 和 (y)。 保留切割得到产品 (xy)，而移除切割得到 (x+y)。 如果两个总和至少为 (2)，则保留削减不会使答案变得更糟。 

这意味着最佳解决方案应创建尽可能多的零件，其总和至少为 (2)。 唯一危险的部分是 sum (1) 部分。 由于每个数组值都是正数，因此 sum (1) 的部分恰好由一个等于 (1) 的数组元素组成。 只要存在相邻部分，这样的部分就应该与相邻部分合并，因为用 (x+1) 替换因子 (1) 和因子 (x) 会严格增加乘积。 

剩下的问题是如何最大化总和至少为 (2) 的部分的数量。 最早可能的剪切位置是当前部分达到总和 (2) 的第一个位置。 在那里切割总是安全的，并为后续零件留下尽可能大的后缀。 贪婪地重复这个过程可以得到完整零件的最大可能数量。 如果扫描结束时有一个未使用的`1`，最后一个元素本身无法形成有效的盈利部分，因此它被合并到前面的部分中。 

蛮力方法之所以有效，是因为它明确地考虑了每个可能的切割位置，但会失败，因为这样的位置数量呈指数级增长。 对 (xy\ge x+y) 的观察将目标从搜索产品更改为最大化有效零件的数量，这可以通过一次从左到右的扫描来完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(n2^n)) | (O(n)) | (O(n)) | 太慢了 |
 | 最佳 | (O(n)) | (O(n)) | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1. 从第一个数组元素开始，并维护当前部分的开头及其运行总和。 当前部分在其总和至少达到 (2) 之前不会被切割，因为当存在另一个元素时，总和为 (1) 的部分永远不会有用。 
2. 从左到右扫描阵列。 每当运行总和至少达到 (2) 时，立即在当前元素之后记录一个剪切并开始一个新部分。 在尽可能早的位置进行切割可以最大限度地增加以后仍然可以创建的完整零件的数量。 
3. 扫描完成后，检查是否有部分后缀未删除。 因为之前的每次切割都是在其总和达到 (2) 时立即进行的，因此未完成的后缀只能具有总和 (1)。 由于所有值都是正数，因此该后缀恰好是一个最终元素，等于`1`。 
4.如果有这样的决赛`1`并且至少存在一个先前的部分，删除先前的剪切并将该先前的部分延伸到最终元素。 这消除了 sum-(1) 部分，合并它会增加乘积。 
5. 如果整个数组由最后一个元素组成，则不可能进行合并。 单元素分区是唯一可能的分区。 
6. 打印每个结果子数组，放置`/`连续部分之间。 

### 为什么它有效

 假设两个相邻部分的和为 (x,y\ge2)。 当它们分开时，它们的贡献是 (xy)，而合并它们时，给出 (x+y)。 自从

 [
 xy-x-y=(x-1)(y-1)-1\ge0,
 ]

 将它们分开永远不会降低产品的质量。 因此，一旦每个部分的总和至少为 (2)，则最大化部分数量就足够了。 

贪婪扫描总是为每个部分选择最早的可能端点。 在到达贪婪端点之前，累积和低于 (2)，因此没有有效部分可以更早结束。 因此，第一次贪婪切割不能晚于任何划分为 sum 至少 (2) 部分的第一次切割。 将相同的参数应用于剩余的后缀可以证明每次后续切割都有相同的属性。 

如果贪婪扫描最终结束`1`，该元素不能形成单独的有效部分。 具有多个部分的任何分区都需要在相应的上一个剪切之后留下后缀，但该后缀将仅包含此单个部分`1`，这对于所有部分的总和至少为 (2) 的分区来说是不可能的。 合并决赛`1`因此，与前一部分的结合是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve(data: str) -> str:
    it = iter(data.split())
    n = int(next(it))
    a = [int(next(it)) for _ in range(n)]

    cuts = []
    start = 0
    current_sum = 0

    for i, x in enumerate(a):
        current_sum += x

        if current_sum >= 2:
            cuts.append(i)
            start = i + 1
            current_sum = 0

    # If one element remains, it must be a single 1.
    # Merge it into the previous part.
    if start < n:
        if cuts:
            cuts.pop()
            cuts.append(n - 1)
        else:
            cuts.append(n - 1)

    parts = []
    start = 0

    for end in cuts:
        parts.append(" ".join(map(str, a[start:end + 1])))
        start = end + 1

    return " / ".join(parts)

def main():
    data = sys.stdin.read()
    sys.stdout.write(solve(data) + "\n")

if __name__ == "__main__":
    main()
```输入被读取`sys.stdin.read()`因为只有一个测试用例，并且整个输入足够小，可以保存在内存中。 这也避免了 (3\cdot10^5) 元素数组问题中的重复解析开销。 

这`current_sum`变量表示当前正在构建的部分的总和。 一旦到达(2)，当前索引就成为剪切端点。 因为所有值都是正数，一旦总和达到 (2)，进一步扩展零件无法帮助我们创建更多零件。 

这`cuts`列表存储每个已完成部分的包含端点。 的`start < n`扫描后，留下一个元素。 它的值必须是`1`。 当存在另一个部分时，最后一个切口将被删除并替换为`n - 1`，将剩余元素合并到前一部分中。 

只有当整个数组是一个最终元素时，才会出现没有先前切割的情况，即`n = 1`和`a[0] = 1`。 在这种情况下，单个元素已经是唯一可能的分区。 

Python 整数不会溢出，尽管此解决方案根本不计算乘积。 这在这里很有用，因为实际的最佳乘积可以有数百万位小数。 该实现仅执行受输入大小和值限制的总和，以及索引操作。 

输出由完整的部分字符串构建并使用`" / "`，这会根据需要在每个斜杠两侧恰好留出一个空格。

 ## 边缘情况

 对于最小输入`1 / 1`，扫描永远不会达到 sum (2)，因此没有完成的切割。 剩余的后缀是整个数组，但没有前面的部分可以将其合并到其中。 该算法因此打印`1`，这是唯一可能的分区。 

为了`3 / 3 1`，第一个元素立即与 sum (3) 形成完整部分。 决赛`1`扫描后仍保留。 由于存在前面的部分，因此算法会删除后面的切割`3`并合并最终元素，产生`3 1`。 产品为(4)，优于单独的产品(3)。 

为了`3 / 1 1 1`，前两个达到和（2），因此算法暂时创建`[1,1]`。 最后一个`1`仍然是单身人士。 最终合并将分区更改为`[1,1,1]`，其因子为 (3)。 这是最优的，因为替代产品 (2\cdot1) 更小。 

对于所有值至少为 (2) 的数组，每个元素都可以立即形成自己的部分。 例如，`4 / 2 2 2 2`变成`2 / 2 / 2 / 2`。 每对相邻因子都满足 (xy\ge x+y)，因此组合任何两个部分都无法改进产品。 因此，贪婪分区具有最大可能的部分数量，并且是最优的。 

对于具有 (300000) 个的最大尺寸输入，每对都达到总和 (2)，因此扫描会创建 150000 个部分并完成，没有剩余。 该算法对每个数组元素执行一个恒定时间决策，并且不需要任何乘积计算，使得大输入的行为与小全 1 示例的行为相同。
