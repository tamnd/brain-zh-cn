 ## 解决方案
 ## 问题理解

 我们有一个正整数数组，我们必须在元素之间进行切割以将其分成连续的段。 每个部分贡献其总和，目标是最大化所有这些部分总和的乘积。 输出本身并不是最大值。 我们必须打印一个达到最大值的分区，使用`/`连续段之间。 

主要的困难在于一次剪辑会同时改变两件事。 它将一个因子（较大部分的总和）替换为两个因子，我们希望将这两个因子的乘积与原始总和进行比较。 由于每个数组值都是正数，因此这种比较具有特别强大的结构。 

该数组最多包含 3⋅10 5 个元素，因此检查所有位置对或更糟糕的是检查所有可能的切割组的算法远远超出了一秒的限制。 二次算法已经在最大尺寸下执行了大约 9⋅10 10 次迭代。 我们需要线性或近线性的结构。 

这些值本身可以大到 10 9 ，但算法只需要涉及它们的比较和加法。 Python 整数还可以避免溢出，尽管该解决方案永远不需要计算巨大的最终结果。 

有几种边缘情况很容易被错误处理。 对于输入```
17
```唯一可能的答案是`7`。 由于无需进行剪切，因此假设至少有两个元素的代码可能会失败。 

为了```
31 1 1
```正确答案是`1 1 1`，没有斜杠。 将其分成三个因子得到 1，而将其保留为一个部分则得到 3。总是分割正数的策略是错误的。 

为了```
31 2 1
```最佳答案是`1 2 1`，因为它的乘积是 4。围绕中间值分裂给出`1 / 2 1`，其乘积为 1⋅3=3。 总是将每个大于一的值放入其自己的段中的策略在这里会失败。 

还有一个不太明显的情况：```
42 1 1 2
```最优划分是`2 1 / 1 2`，给出 3⋅3=9。 将两个数放在两边得到 4⋅2=8。 因此，两个较大值之间的值不能简单地分配给一侧。 它们必须得到最佳分配。 

## 方法

 直接的暴力解决方案考虑了每一个可能的切割位置。 连续元素之间有 n−1 个间隙，每个间隙可以包含切割，也可以不包含切割，因此正好有 2 n−1 个分区。 对于每个分区，我们可以计算段总和及其乘积并保留最好的一个。 在最坏的情况下，简单的实现需要 θ(n2 n−1 ) 算术运算，因为分区可以包含 θ(n) 个段。 即使是增量地维持乘积的改进枚举仍然具有 θ(2 n ) 状态，这对于 n=3⋅10 5 来说是没有希望的。 

自然的动态规划公式也太慢。 如果`dp[i]`是以位置 i 结尾的前缀的最佳乘积，我们可以尝试每个先前的剪切位置并使用相应后缀的总和。 这给出了 O(n 2 )，这已经太大了。 

关键的观察结果来自于将一个片段与其内部可能的切口进行比较。 假设一个线段的总和为 x+y，切割它会产生总和为 x 和 y 的两个连续片段。 旧的贡献是x+y，而新的贡献是xy。 由于 x 和 y 是正整数，

 xy≥x+y

 每当 x,y≥2 时，因为

 xy−x−y=(x−1)(y−1)−1≥0。 

因此，每当潜在削减的双方的总和至少为 2 时，进行削减永远不会减少答案。 

这会产生严重的后果。 由于每个大于 1 的数组元素的总和至少为 2，因此可以选择最佳分区，以便没有段包含两个大于 1 的元素。 如果确实如此，我们可以在它们之间进行切换，而不会使结果变得更糟。 

这意味着最优解决方案中的每个段最多有一个大于 1 的元素。 唯一剩下的问题是如何处理一系列的问题。 

考虑两个连续大于 1 的值 x 和 y，它们之间正好有 k 个：

 x, k 1,1,…,1 ​ ,y。 

k 个必须在包含 x 的段和包含 y 的段之间划分。 如果 l 个向左移动，k−l 个向右移动，则它们的贡献为

 (x+l)(y+k−l)。 

这两个因素的总和是固定的：

 x+l+y+k−l=x+y+k。 

对于两个总和固定的正数，当它们尽可能接近时，它们的乘积最大。 因此我们只需要选择 l 使得 x+l 尽可能接近 x+y+k 的一半。 

前导的必须全部加入第一个大于 1 的值，而尾随的必须全部加入最后一个这样的值。 如果整个数组由 1 组成，则将整个数组保留为一个段是最佳的。 

这将整个问题简化为扫描一次数组，找到大于 1 的值以及它们之间的运行，并独立决定每个运行的分割。

 ## 算法演练

 1. 找到每个值大于 1 的位置。 这些值将作为最佳细分的锚点。 如果没有这样的位置，则数组完全由 1 组成，因此将整个数组作为一个段输出。 
2. 从第一个大于 1 的值及其前面出现的所有值开始当前段。 那些领先的公司无法单独盈利，因为乘以一倍比将一倍添加到现有细分市场更糟糕。 
3. 处理每对大于 1 的连续值，将它们称为 x 和 y。 数一下它们之间的 k 个。 
4. 假设其中 l 个被分配给包含 x 的段。 剩余的 k−l 个属于包含 y 的段，因此两个相关和是 x+l 和 y+k−l。 
5. 选择最接近的 l

 2 y+k−x ​ .

 该表达式来自使 x+l 尽可能接近固定总数 x+y+k 的一半。 将结果限制在区间 [0,k] 内，因为我们不能向左侧分配负数或超过所有 k 个数。 

1. 将这 l 个附加到当前段并以斜杠结束该段。 从剩余的 k−l 个开始下一个段，后跟 y。 
2. 处理完大于 1 的最终值后，将所有尾随值附加到其段中。 由此产生的段形成有效的分区并实现最大乘积。 

### 为什么它有效

 考虑任何包含两个大于一的元素的段。 在这两个元素之间切割得到两个子段，其总和都至少为二。 如果它们的和是 x 和 y，则用 xy 替换因子 x+y 不会减少乘积。 重复此操作会得到一个最佳分区，其中每个段最多包含一个大于 1 的值。

因此，所有选择都仅限于两个大于 1 的连续值之间的一系列选择。 这样的运行不会与任何其他运行交互，因为它仅更改两个相邻段的总和。 对于 x 和 y 之间的 k 个数，其贡献为 (x+l)(y+k−l)，其两个因子具有固定和。 当两个具有固定和的正数尽可能相等时，它们的乘积会最大化，这正是所选 l 的作用。 前导数组和尾随数组只有一个可能的有用邻居，而全一数组最好保留为一个段。 因此，每个独立部分都是最优的，并且它们的组合是全局最优的。 

## Python 解决方案```python
Pythonimport sysinput = sys.stdin.readline

def solve():    n = int(input())    a = list(map(int, input().split()))
    big = [i for i, x in enumerate(a) if x > 1]
    if not big:        print(" ".join(map(str, a)))        return
    parts = []
    first = big[0]    current = a[:first + 1]
    for p in range(1, len(big)):        prev = big[p - 1]        cur = big[p]
        k = cur - prev - 1        x = a[prev]        y = a[cur]
        # Maximize (x + l) * (y + k - l).        # The ideal value is (y + k - x) / 2.        l = (y + k - x) // 2        l = max(0, min(k, l))
        current.extend([1] * l)        parts.append(current)
        current = [1] * (k - l)        current.append(y)
    last = big[-1]    current.extend(a[last + 1:])    parts.append(current)
    output = []    for i, part in enumerate(parts):        if i:            output.append("/")        output.extend(map(str, part))
    print(" ".join(output))

if __name__ == "__main__":    solve()
```这`big`数组精确存储值超过 1 的位置。 这些是唯一可以充当最佳细分的中心元素的值。 

最初的`current`段包含第一个锚点和每个前导锚点。 切片`a[:first + 1]`保留原始顺序并处理第一个锚点之前的边界，而无需特殊的输出情况。 

对于两个连续的锚点，`k`是严格位于其位置之间的个数。 变量`l`是分配给左段的编号。 表达式`(y + k - x) // 2`是理想值的整数下限。 当理想点恰好位于两个整数之间时，任一相邻整数都是最佳的，因此取底就足够了。 

这`max`和`min`边界处需要呼叫。 例如，如果 x 远大于 y+k，则理想值可以为负，这意味着所有的都应该向右。 如果 y 更大，则所有的都应该向左移动。 

当前段在创建下一个段之前完成。 这个顺序很重要，因为左边的段必须包含第一个`l`和正确的段必须包含剩余的`k-l`那些。 在处理完所有内部间隙后，将附加最终的尾部间隙。 

该代码从不计算最终产品。 该乘积可以有大量的数字，而问题只需要最大化分区。 因此，Python 的任意精度整数甚至与主要算法无关。

## 正确的结构洞察

 决定性的比较不仅仅是切割双方的总和是否至少为 2。 对于总和 x,y,

 xy≥x+y

 对于 x,y≥2 成立，特别是当 x=y=2 时相等。 

因此，每个分段都可以被细化，直到每个结果分段的总和为 1 或 2，除非分隔分段会改变相邻选择的可能性。 由于当另一个正值段可以吸收总和为 1 的段时，它总是有害的，因此唯一有用的孤立小段是总和为 2 的段。 

因为所有数组元素都是正数，所以 sum 为 2 的段只能是`[2]`或者`[1, 1]`。 每个大于 2 的元素必须与最佳分区中的其他元素隔离，而等于 2 的值可以与相邻的一对元素竞争。 

这导致了更简单的本地规则。 每个大于二的值都应该是自己的段，相邻的段根据产品比较进行分配。 等于 2 的值可以被完全视为由两个 1 组成的段，并且当无法将 1 的运行有效地附加到相邻的较大段时，必须将它们分为两个组。 

由此产生的构造更自然地表示为动态程序溢出，因为围绕值二的边界交互可以创建等积替代方案。
