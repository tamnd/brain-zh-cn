 ## 解决方案
 ## 问题理解

 我们有一个数组`a`的`n`数字，其中每个数字都是整数`0`到`b - 1`。 从左到右读取数组给出`n`- 基数中的数字`b`。 我们需要一个严格大于这个数字且所有数字都不同的最小数字。 已知第一个数字不为零，并且保证存在答案。 

关键的困难在于“下一个”是数字顺序，对于两个固定长度的碱基来说`b`Numbers 正是其数字数组的字典顺序。 所以我们要尽可能晚地改变数组。 一旦我们决定扩大一个位置，后面的每个位置都应该尽可能小，同时保持所有数字不同。 

两个都`n`和`b`可以大到`3 * 10^5`。 这排除了任何尝试多种可能数字的情况，甚至排除了任何二次的情况`n`。 在 2 秒的限制下，我们想要大致线性或`O(n log b)`工作。 基数可能足够大，因此我们还需要小心整个数字范围内的操作，尽管`O(b)`仍然可以接受，因为`b`具有相同的上限`n`。 

在一些边缘情况下，简单的实现可能会悄无声息地出错。 首先，输入本身可能包含重复的数字。 例如，```
3 10
1 1 9
```有答案`1 2 0`，不是通过简单修改最后一位数字得到的。 前缀`1 1`已经无效了，所以最后一个位置不能作为我们把数字变大的地方。 

第二个问题是最后一位数字可能无法递增，因为每个较大的数字都已被前缀使用。 例如，```
4 4
3 2 0 1
```无法在最终位置增加，因为前缀已使用`0`,`2`， 和`3`。 正确答案是`3 2 1 0`，通过改变第三个位置得到。 

当唯一可能的增加发生在第一个位置时，就会出现第三种边缘情况。 例如，```
3 4
1 3 3
```有答案`2 0 1`。 一旦第一个数字变成`2`，其余位置必须使用最小的两个未使用的数字。 粗心的实现可能会错误地保留原始重复项之一`3`s，即使后缀必须包含不同的数字。 

最后，可以通过改变非最终位置从已经不同的输入获得答案。 为了```
3 4
1 2 3
```答案是`1 3 0`。 保留前缀`1`，增加`2`到`3`，然后用最小的可用数字填充后缀给出大于的第一个有效数字`123`。 

## 方法

 最直接的方法是从输入数字之后立即开始枚举候选数字。 对于每个候选人，我们可以检查是否所有`n`数字是不同的。 支票本身需要`O(n)`时间，所以如果我们检查`K`连续候选人的成本是`O(Kn)`。 在最坏的情况下，在达到有效数量之前，候选者的数量可能呈指数级增长，最多`b^n`可能的`n`- 数字数组。 因此最坏情况的界限是`O(n b^n)`，这对于`n`最多`3 * 10^5`。 

蛮力方法确实有一个有用的属性：它准确地告诉我们所需的答案是什么样的。 我们希望从右边开始的第一个位置可以增加一位数字，而该位置之前的所有内容都保持不变。 增加后，后缀应该是尽可能小的有效后缀。 

这一观察消除了枚举数字的需要。 假设我们选择位置`i`作为第一个改变的位置。 前缀`a[0:i]`必须已经由不同的数字组成。 替换数字必须严格大于`a[i]`并且不能出现在该前缀中。 在所有这些选择中，我们想要最小的一个。 一旦选择了该数字，后缀应仅包含按升序排列的最小未使用数字。 

剩下的数据结构问题是找到大于的最小未使用数字`a[i]`。 自从`b`取决于`3 * 10^5`，芬威克树可以维护当前未使用的数字集并找到`k`第 - 个未使用的数字`O(log b)`时间。 我们从右到左扫描位置，同时动态维护前缀中出现的数字。 

蛮力之所以有效，是因为检查候选项最终会找到第一个有效的较大数字，但会失败，因为候选项可能太多。 观察到只有第一个更改的位置很重要，这让我们可以用单个从右到左的扫描和后续查询来替换指数枚举。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n b^n)`最坏的情况|`O(n + b)`| 太慢了 |
 | 最佳|`O(n log b + b)`|`O(n + b)`| 已接受 |

 ## 算法演练

 1. 构建前缀频率数组`a[0:n-1]`，因为当我们第一次检查位置时`n-1`，每个前面的数字都属于未更改的前缀。 同时，初始化一个 Fenwick 树，其中包含该前缀当前未使用的每个数字。 
2. 维护`bad`，当前前缀中出现频率至少为 2 的数字值的数量。 前缀在以下情况下可用：`bad == 0`。 我们明确需要这个，因为不能保证原始数组包含不同的数字。 
3. 开始于`i = n - 1`并移动`i`趋向于零。 在位置`i`, 前面的前缀是`a[0:i]`。 如果`bad`不为零，则该前缀不能出现在任何有效答案中，因此该位置不能是第一个更改的位置。 
4. 如果前缀不同，则在 Fenwick 树中查询严格大于的最小未使用数字`a[i]`。 如果有这样一个数字`x`存在，那么`a[0:i] + [x]`是大于该位置的原始数字的最小可能前缀`i`。 
5.一次`x`找到后，通过扫描来自的数字来构建后缀`0`向上并取前缀未使用且不等于的最小数字`x`。 这些正是字典顺序上最小的可能后缀数字，因此此选择给出了该固定位置的最小数字`i`。 
6. 如果无效`x`存在于位置`i`，移至`i - 1`。 代表新的前缀`a[0:i-1]`， 消除`a[i-1]`从当前前缀计数开始，如果该数字的计数变为零，则将该数字标记为未使用。 更新`bad`如果删除该事件就可以消除重复的事件。 
7. 我们可以构建答案的第一个位置是要更改的正确位置。 我们从右向左扫描，因此每个后面的位置都已被证明是不可能的，而改变较早的位置会产生更大的数字。 

### 为什么它有效

 考虑第一个位置`i`算法成功的地方。 之后的每个位置`i`首先进行了测试，无法在保留其前缀的同时产生有效的较大数字。 因此，之后的答案不能与原始答案不同`i`。 

在位置`i`, 前缀`a[0:i]`是独特的，因此可以安全地保存。 该算法选择大于的最小未使用数字`a[i]`，这是使该位置的结果数字更大的最小可能数字。 任何较小的替换都无法使数字更大，而任何较大的替换都会产生超出必要的数字。 

替换后，所有剩余位置均按升序填充最小的可用数字。 由于前缀和替换已经固定，因此这是字典顺序上最小的有效后缀。 因此，构造的数字大于输入，具有不同的数字，并且不存在更小的有效较大数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, pos, delta):
        pos += 1
        while pos <= self.n:
            self.bit[pos] += delta
            pos += pos & -pos

    def prefix_sum(self, pos):
        """Number of elements in [0, pos)."""
        res = 0
        while pos > 0:
            res += self.bit[pos]
            pos -= pos & -pos
        return res

    def kth(self, k):
        """Return the 0-based index of the k-th present element."""
        idx = 0
        step = 1 << (self.n.bit_length() - 1)

        while step:
            nxt = idx + step
            if nxt <= self.n and self.bit[nxt] < k:
                idx = nxt
                k -= self.bit[nxt]
            step >>= 1

        return idx

def solve_case(n, b, a):
    # The prefix before position n-1.
    cnt = [0] * b
    for i in range(n - 1):
        cnt[a[i]] += 1

    # Number of digit values appearing at least twice in the prefix.
    bad = sum(c >= 2 for c in cnt)

    # Fenwick tree stores currently unused digits.
    fw = Fenwick(b)
    for d in range(b):
        fw.add(d, 1)

    # Remove all digits used by the prefix from the available set.
    for d in range(b):
        if cnt[d]:
            fw.add(d, -1)

    for i in range(n - 1, -1, -1):
        if bad == 0:
            # Number of unused digits <= a[i].
            le = fw.prefix_sum(a[i] + 1)
            total = fw.prefix_sum(b)

            # We need the first unused digit strictly greater than a[i].
            k = le + 1

            if k <= total:
                x = fw.kth(k)

                # The prefix is already distinct, and x is unused.
                ans = a[:i] + [x]

                # Fill the suffix with the smallest remaining digits.
                need = n - i - 1
                for d in range(b):
                    if need == 0:
                        break
                    if cnt[d] == 0 and d != x:
                        ans.append(d)
                        need -= 1

                return ans

        if i > 0:
            # Move from prefix a[:i] to prefix a[:i-1].
            v = a[i - 1]

            if cnt[v] == 2:
                bad -= 1

            cnt[v] -= 1

            if cnt[v] == 0:
                fw.add(v, 1)

    # The statement guarantees that an answer exists.
    return []

def main():
    n, b = map(int, input().split())
    a = list(map(int, input().split()))

    ans = solve_case(n, b, a)
    print(*ans)

if __name__ == "__main__":
    main()
```频率数组描述了当前未改变的前缀。 频率大于 1 意味着前缀永远不可能成为有效答案的一部分，因此`bad`让我们在恒定时间内测试前缀有效性。 

Fenwick 树恰好包含前缀中缺少的数字。`prefix_sum(a[i] + 1)`计算可用数字`0`通过`a[i]`，所以下一个可用数字有排名`le + 1`。 这`kth`操作将该排名转换为实际数字`O(log b)`时间。 

循环从最终位置之前的前缀开始，每当向左移动时就会删除一个元素。 此顺序是关键的边界细节。 迭代时`i`,`cnt`必须准确描述`a[0:i]`， 不是`a[0:i+1]`。 

当频率从`2`到`1`，一个重复的数字消失，所以`bad`减少。 当频率从`1`到`0`，该数字在 Fenwick 树中再次可用。 当计数保持正数时，我们永远不需要添加一个数字。 

后缀结构故意从零向上扫描。 选定的替代品`x`被排除，前缀中已经存在的所有数字也被排除。 循环正好需要`n - i - 1`数字，这是可能的，因为问题保证存在一些有效答案，并且存在`n`-digit 不同的数字也意味着`b >= n`。 

没有基数的整数转换`b`数字，因此 Python 整数大小无关紧要。 答案被处理为数字数组，这也是必要的，因为`b`可以比十大得多。 

## 工作示例

 ### 示例 1

 对于```
3 10
9 2 6
```输入在每个位置都有一个不同的前缀。 最右边的数字是`6`，并且最小的未使用数字大于`6`是`7`，这样我们就可以立即改变最终位置。 

|`i`| 前缀 |`a[i]`| 未使用的较大数字 | 行动|
 | --- | --- | --- | --- | --- |
 | 2 |`9 2`| 6 | 7 | 选择`7`|

 结果数字是`9 2 7`。 没有保留后缀，因此这立即是大于输入的最小有效数字。 

### 示例 2

 对于```
4 11
10 5 5 1
```最终位置无法使用，因为它的前缀包含两个副本`5`。 我们向左移动，直到前缀变得清晰。 

|`i`| 前缀 |`bad`|`a[i]`| 最小的未使用的较大数字 | 行动|
 | --- | --- | --- | --- | --- | --- |
 | 3 |`10 5 5`| 1 | 1 | 2 | 不能使用前缀 |
 | 2 |`10 5`| 0 | 5 | 6 | 选择`6`|

 选择后`6`，前缀是`10 5 6`。 唯一剩余的位置应接收最小的未使用数字，即`0`。 

结果是`10 5 6 0`。 该轨迹说明了为什么我们不能简单地在最终位置寻找更大的值。 在保留该位置之前，前缀必须已经有效。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(n log b + b)`| 有`n`后续查询或前缀更新，每次都采用`O(log b)`，后面最多有一个`O(b)`后缀构造。 |
 | 空间|`O(n + b)`| 输入、频率数组、芬威克树和输出都使用线性空间。 |

 和`n, b <= 3 * 10^5`，该算法仅执行几百万次 Fenwick 运算加上数字范围内的一次扫描。 这完全在 2 秒和 256 MB 限制的预期范围内，而候选数字的枚举则呈指数级增长。

 ## 边缘情况

 对于重复前缀的情况```
4 5
2 2 2 2
```第一个测试的位置是`i = 3`, 带前缀`2 2 2`。 其数字出现的频率`2`是三，所以`bad > 0`并且该职位被拒绝。 在`i = 2`，前缀是`2 2`，仍然无效。 在`i = 1`，前缀只是`2`，这是独特的。 最小的未使用数字大于`2`是`3`，剩余的最小数字是`0`和`1`，生产`2 3 0 1`。 

对于必须在一开始就发生变化的情况，```
3 4
1 3 3
```最后一个位置之前的前缀是`1 3`，这是不同的，但没有未使用的数字大于`3`因为上面唯一的数字必须至少是`4`，基地外。 搬迁至`i = 1`, 前缀`1`是不同的，但同样没有未使用的数字大于`3`。 在`i = 0`，最小的未使用数字大于`1`是`2`。 然后后缀使用`0`和`3`, 给予`2 0 3`如果`3`可用。 然而，实际最小的后缀是`0 1`，因为原来的数字`3`不是保留前缀的一部分，不需要重用。 因此正确的输出是`2 0 1`。 这说明了为什么后缀必须从新前缀使用的数字集重建，而不是从输入复制。 

对于本案```
3 4
1 2 3
```位置之前的前缀`2`是`1 2`，但当前数字`3`没有更大的未使用数字。 我们删除`2`从维护的前缀和测试位置`1`。 前缀`1`是不同的，并且`3`是大于的最小未使用数字`2`。 选择后`3`，最小的未使用后缀数字是`0`, 给予`1 3 0`。 更改第一个位置会产生更大的数字，因此停在位置`1`这正是从右到左扫描的目的。 

对于边界情况```
4 4
3 2 0 1
```最后一位数字之前的前缀是`3 2 0`，这是不同的，但是当前数字`1`不能增加，因为每个较大的 4 基数字，即`2`和`3`，已被使用。 算法移动到位置`2`，其中前缀是`3 2`。 数字`1`未使用且大于当前值`0`，因此它成为替代品。 剩余的最小未使用数字是`0`，生产`3 2 1 0`。 由于更改后的位置尽可能靠右，因此不存在更小的有效较大数字。
