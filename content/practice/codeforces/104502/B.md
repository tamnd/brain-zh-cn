 ## 解决方案
 ## 问题理解

 我们给定一个字符串和固定长度$k$。 我们必须恰好删除一个长度连续的子串$k$，然后将其余部分连接在一起。 这会产生一个新的长度字符串$|s| - k$。 在删除的段的所有可能选择中，我们想要字典顺序最小的结果字符串。 

关键点是删除位置以结构化方式更改字符串：删除块之前的所有内容都保持在原位，删除块之后的所有内容左移$k$。 因此，每次删除选择都定义了前缀和后缀的不同“拼接”。 

总体而言，约束很严格：跨测试用例的总字符串长度最多为$4 \cdot 10^5$，因此任何尝试所有删除并显式构造并重复比较完整字符串的解决方案$O(n)$每次尝试都会崩溃为二次行为。 甚至$O(n^2)$总工作量太大，因此真正的目标是将每个候选比较时间减少到接近恒定或对数时间。 

当贪婪地思考删除位置时，会出现一个微妙的陷阱。 局部最小化结果前缀中的字符并不能保证全局最优性，因为稍早或稍晚删除可能会改变字符串的对齐方式。 两个不同的删除可能在发散之前就一个长前缀达成一致，并且该发散决定了答案。 因此，任何正确的解决方案都必须按字典顺序比较整个结果字符串，而不仅仅是删除周围的直接邻域。 

另一个边缘情况是最佳删除从最前面删除字符。 在某些输入中，最佳策略是删除第一个块，有效地将字符串向左移动以更早地暴露更小的字符。 避免早期删除的幼稚方法将完全错过这些情况。 

## 方法

 直接的暴力策略会尝试所有可能的起始位置$a$, 构造删除后的结果字符串$s[a : a+k-1]$，然后比较所有结果。 这是正确的，因为它明确评估每个有效结果，但速度太慢。 构建一个候选字符串的成本$O(n)$，并且有$O(n)$的选择$a$，导致$O(n^2)$在最坏的情况下每个测试用例的工作量远远超出了限制$n$总和为$4 \cdot 10^5$。 

关键的观察是，我们实际上不需要完全具体化每个候选字符串来比较它们。 每个结果只是原始字符串的确定性重新索引：我们要么从前缀或后缀中获取字符，跳过单个阻塞间隔。 如果我们能够有效地比较两个这样的“虚拟字符串”，我们就可以在不构建所有结果的情况下搜索最佳删除。 

这减少了维护由删除的间隔隐式定义的许多字符串的问题，并支持它们中任意两个之间的字典顺序比较。 实现此目的的自然工具是散列与二分搜索相结合以查找第一个不同的位置。 原始字符串上的前缀哈希允许我们在恒定时间内计算任何子字符串哈希，并且由于单个删除的间隙，结果字符串的每个子字符串最多对应于原始字符串的两个子字符串。 该结构足以比较任何两个候选人$O(\log n)$，启用对所有删除位置的全面扫描$O(n \log n)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(n)$| 太慢了|
 | 对所有删除进行哈希+二进制比较 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们对待每个可能的删除开始$a$作为定义候选结果字符串$x_a$，这是$s[0:a)$和$s[a+k:n)$。 我们的任务是找到所有中按字典顺序最小的$x_a$。 

### 步骤

 1. 预先计算原始字符串的前缀哈希值和幂。 

这使得我们能够在常数时间内查询任意子串哈希，这是快速比较的基础。 
2. 定义一个帮助器，计算候选字符串的任意子字符串的哈希值$x_a$。 

中的一个子串$x_a$要么完全映射在前缀部分内，要么完全映射在后缀部分内，或者跨越两者。 在交叉情况下，它分成两个原始子字符串，我们使用预先计算的幂组合它们的哈希值。 
3. 定义一个函数来比较两个候选者$x_a$和$x_b$。 

我们对它们的最长公共前缀的长度执行二分搜索。 在每个中点，我们比较相应子字符串的哈希值$x_a$和$x_b$。 这决定了它们是否匹配到该长度。 
4. 一旦找到第一个不同的位置，就比较两个候选中该位置的字符。 

字符较小的字符按字典顺序排列较小。 
5. 迭代所有有效的删除位置$a$，保持迄今为止发现的最好的一个。 

使用比较函数将每个新候选者与当前最佳候选者进行比较，然后用更好的候选者替换它。 
6. 处理完所有位置后，通过连接最佳的前缀和后缀来重建最终答案$a$。 

### 为什么它有效

 每个候选字符串完全由单个删除间隔确定，字典顺序仅取决于两个候选字符串之间的第一个不匹配。 散列结构保证我们可以有效地检测任何前缀的相等性，而二分搜索确保我们无需线性扫描即可找到第一个不匹配的位置。 因为我们总是在正确的字典比较下保留迄今为止看到的最佳候选，所以最终存储的删除位置必须产生全局最小的结果字符串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Hash:
    def __init__(self, s, base=91138233, mod=10**9+7):
        self.mod = mod
        self.base = base
        n = len(s)
        self.pow = [1] * (n + 1)
        self.h = [0] * (n + 1)
        for i, c in enumerate(s):
            self.pow[i + 1] = (self.pow[i] * base) % mod
            self.h[i + 1] = (self.h[i] * base + (ord(c) - 96)) % mod

    def get(self, l, r):
        return (self.h[r] - self.h[l] * self.pow[r - l]) % self.mod

def solve():
    s, k = input().split()
    k = int(k)
    n = len(s)

    hs = Hash(s)

    def get_hash(l, r):
        return hs.get(l, r)

    def candidate_hash(a, l, r):
        # substring of x_a in [l, r)
        # maps to original string with gap [a, a+k)
        left_len = max(0, min(r, a) - l)
        h = 0

        if left_len > 0:
            h = (h * hs.base + get_hash(l, l + left_len)) % hs.mod

        if r > a:
            l2 = max(l, a)
            r2 = r
            if l2 < a + k:
                l2 = a + k
            if l2 < r2:
                h = (h * hs.base + get_hash(l2, r2)) % hs.mod

        return h

    def compare(a, b):
        lo, hi = 0, n - k
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if candidate_hash(a, 0, mid) == candidate_hash(b, 0, mid):
                lo = mid
            else:
                hi = mid - 1

        if lo == n - k:
            return 0

        ca = get_char(a, lo)
        cb = get_char(b, lo)
        return -1 if ca < cb else 1

    def get_char(a, i):
        if i < a:
            return s[i]
        return s[i + k]

    best = 0
    for a in range(n - k + 1):
        if compare(a, best) < 0:
            best = a

    res = s[:best] + s[best + k:]
    print(res)

t = int(input())
for _ in range(t):
    solve()
```该解决方案在原始字符串上构建哈希结构，以便任何子字符串查询都是恒定时间。 每个候选删除都通过索引映射隐式表示，因此我们在比较期间从不构造中间字符串。 

比较函数依赖于对答案长度的二分搜索来定位第一个不匹配。 在每一步中，它都会比较两个候选字符串的前缀哈希。 一旦找到分歧点，我们就通过使用删除偏移量直接将字符索引映射回原始字符串来解决它。 

一个常见的实现陷阱是对已删除区间的子字符串映射进行错误处理。 候选的任何子串最多可以分裂成两个原始片段，并且在跨越间隙时忘记调整索引会导致不正确的哈希值和错误的比较。

 ## 边缘情况

 一个微妙的边缘情况是所有字符都相同。 每次删除都会产生相同的结果，因此任何尝试通过提前停止进行优化的实现都不能意外地跳过有效的候选者。 该算法仍然可以正确评估比较，因为所有前缀哈希都匹配，并且最终的平局打破步骤自然会保留第一个候选者。 

另一种情况是当最佳删除与字符串的前缀重叠时。 例如，删除第一个$k$人物。 索引映射确保所有比较都正确地将后缀视为已移位，并且结果字符串仍被评估为从位置零开始的完整候选字符​​串。 

第三种情况是当$k = 1$，其中每个候选者仅相差一个被删除的字符。 在这里，词典结构变得高度敏感，二分搜索比较对于避免逐字符扫描每对至关重要。
