 ## 解决方案
 ## 问题理解

 我们正在使用通过整数的二进制表示形式定义的函数。 对于任意正整数$x$，我们查看其不带前导零的二进制形式。 然后，我们扫描相邻位并计算位值从 0 变为 1 或从 1 变为 0 的次数。该计数就是值$f(x)$。 

每个查询给出两个数字$n$和$k$。 任务是计算有多少个整数$x$在范围内$1 \le x \le n$正好有$k$二进制表示中相邻位之间的转换。 

约束条件$n \le 2^{60} - 1$意味着每个数字最多可以容纳 60 位。 这立即表明了对位的数字动态编程方法，因为对所有值进行强力迭代直到$n$是不可行的，当$n$很大并且有多达$10^5$查询。 

一个天真的想法是计算$f(x)$对于每个$x$最多$n$。 这是不可能的，因为即使是单个查询也可以有$n$靠近$10^{18}$，并且对每个数字进行位扫描就已经超出了时间限制。 

当尝试在不考虑查询独立性的情况下预先计算达到限制的值时，会出现更微妙的失败情况。 例如，如果假设所有查询共享相同的预计算数组，直到最大$n$，这在内存和预处理时间上仍然失败，因为$n$可以是$2^{60}$。 

另一个重要的边缘情况是二进制长度为 1 的小值。$x = 1$,$f(x) = 0$，并且任何 DP 都必须正确处理不存在相邻对的事实。 

## 方法

 暴力解决方案很简单。 对于每个数字$x$从 1 到$n$，将其转换为二进制并计算连续位不同的次数。 这需要$O(\log x)$每个号码，因此单次查询成本$O(n \log n)$。 和$n$最多$10^{18}$，这是完全不可行的。 

关键的观察结果是，我们对单个数字不感兴趣，而是对长度最大为 60 且转换次数有限的二进制字符串感兴趣。 这是一个经典的位上的数字 DP：我们不是直接枚举数字，而是从最高有效位向下一点一点地构建它们，跟踪发生了多少次转换以及我们是否仍然严格遵守前缀$n$。 

重要的结构是，一旦知道前一位，添加新位要么会增加转换计数，要么不会增加。 这意味着状态只需要记住位置、前一个位、到目前为止的转换次数以及我们是否仍然受到前缀的约束$n$。 

这减少了枚举问题$n$最多可枚举的数字$60 \times 2 \times 60 \times 2$每个查询的状态，这很容易足够快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n \log n)$每个查询|$O(1)$| 太慢了|
 | 数字DP |$O(60 \cdot k \cdot 2)$每个查询|$O(60 \cdot k \cdot 2)$| 已接受 |

 ## 算法演练

 我们使用二进制表示上的位 DP 独立处理每个查询$n$。 

1. 转换$n$从最高有效位到最低有效位转换为 60 位二进制数组。 我们使用固定长度，以便所有数字统一对齐。 这避免了在 DP 内部处理可变长度的边缘情况。 
2. 定义位置上的 DP 函数。 在每个位置，我们决定是否放置 0 或 1，遵守不超过前缀的约束$n$如果我们仍然紧张的话。 
3. DP状态包括当前位位置，我们是否紧跟$n$、前一个放置的位以及当前的转换数量。 我们还为起始位置添加了一个特殊的“尚无前一个位”状态，以便第一个选择的位不会被错误地视为转换。 
4. 当从一位转换到下一位时，我们更新转换计数。 如果前一位存在并且与当前位不同，我们将计数加一。 否则它保持不变。 
5. 我们仅在处理完所有位后在最终状态累积结果。 如果转换计数等于$k$，我们将答案加 1。 
6. 对于每个查询，我们对表示 1 到 1 之间数字的所有有效 DP 路径求和$n$。 我们确保排除全零数，因为它不是正数。 

### 为什么它有效

 范围内的每个整数$[1, n]$唯一对应于长度最多为 60 的二进制字符串，该字符串按字典顺序受以下二进制表示形式限制$n$。 DP 精确地枚举这些字符串而不重复。 转换计数器仅根据相邻位确定性地演化，因此 DP 状态完全捕获计算所需的所有信息$f(x)$。 因为每个有效数字都只表示一次并且无效数字不会超过$n$在严格约束下允许，最终的总和精确地计算出所需的集合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXB = 60

def solve_case(n, k):
    bits = [(n >> i) & 1 for i in range(MAXB - 1, -1, -1)]

    from functools import lru_cache

    @lru_cache(None)
    def dp(pos, tight, started, prev, cnt):
        if cnt > k:
            return 0
        if pos == MAXB:
            return 1 if started and cnt == k else 0

        limit = bits[pos] if tight else 1
        res = 0

        for b in (0, 1):
            if b > limit:
                continue
            ntight = tight and (b == limit)

            if not started:
                if b == 0:
                    res += dp(pos + 1, ntight, False, 0, cnt)
                else:
                    res += dp(pos + 1, ntight, True, b, cnt)
            else:
                ncnt = cnt + (b != prev)
                res += dp(pos + 1, ntight, True, b, ncnt)

        return res

    return dp(0, True, False, 0, 0)

def main():
    q = int(input())
    for _ in range(q):
        n, k = map(int, input().split())
        print(solve_case(n, k))

if __name__ == "__main__":
    main()
```DP 作为记忆递归来实现。 状态显式跟踪我们是否已经开始放置二进制表示； 这可以避免错误地将前导零计算为数字的一部分。 这`tight`标志强制执行上限$n$一点一点。 

转换逻辑仔细地区分第一个非零位和后续位。 这是至关重要的，因为定义$f(x)$仅适用于不带前导零的实际二进制表示。 

修剪条件`cnt > k`防止对已经超过目标转换数量的状态进行不必要的探索。

 ## 边缘情况

 一个重要的边缘情况是当$x$是二的幂。 它的二进制表示形式是 1 后跟 0，因此它始终只有一个转换。 DP 自然地处理这个问题，因为第一位是 1，所有后续位都是 0，恰好贡献了从 1 到 0 的一次变化。 

另一个边缘情况是$x = 1$。 二进制表示的长度为 1，因此不存在相邻对。 DP 在放置单个 1 后立即到达终止状态，并且转换计数保持为零，与定义匹配。 

前导零处理也很关键。 如果没有`started`标志，像“000101”这样的字符串会错误地提供额外的转换。 DP 通过忽略全零前缀并仅在放置第一个 1 后才开始转换计数来避免这种情况。
