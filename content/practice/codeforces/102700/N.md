 ## 解决方案
 ## 问题理解

 乔兰尼的一年包括`n`天。 每天她都可以尝试一次时间机器。 如果机器成功，她马上就到了下一个生日。 成功概率是给定的`n`值，但它们的顺序是随机排列的，因此每个排列的可能性都是相等的。 

对于一份固定订单`p_1, p_2, ..., p_n`， 让`T`是她等待的天数。 如果机器第一次出现故障`k`天，她已经等了`k`天。 期望的一种方便形式是

 [
 E[T] = \sum_{k=1}^{n}\Pr(T\ge k)。 
]

为了`T >= k`，第一个`k`尝试都必须失败。 如果我们写

 [
 q_i=1-p_i,
 ]

 那么对于固定排列，

 \sum_{k=1}^{n}q_1q_2\cdots q_k。 
]

 任务是对所有数量进行平均`n!`可能的排列。 

官方的限制允许`n`最多`5000`，时间限制为 1 秒，内存为 512 MB。 阶乘时间算法是立即不可能的，甚至`O(n^3)`动态程序太大了。 一个`O(n^2)`算法是自然目标，需要大约 1250 万次状态更新`n=5000`。 内存限制很容易容纳一维 DP。 

有几种边界情况暴露了常见的错误。 和```
1
0
```机器总是出故障，所以答案是正确的`1`。 仅计算成功尝试的公式可能会错误地返回零。 和```
1
1
```答案是`0`，因为第一次尝试总是成功的。 和```
2
0 1
```两个同样可能的订单是`[0,1]`和`[1,0]`。 他们的等待时间是`1`和`0`，所以答案是`0.5`。 将概率视为独立随机变量而不是无放回抽样的解决方案会导致这种情况错误。 最后，不得对重复概率进行去重。 随机过程是位置的排列，因此即使相同的值仍然占据不同的位置`n!`等概率排列。 

## 方法

 直接的方法是枚举概率数组的每个排列。 对于每个排列，扫描其天数并使用失败概率计算预期等待时间。 这是正确的，因为它明确地以其规定的概率评估每个可能的隐藏排序。 不幸的是，有`n!`排列，并评估一个需要`O(n)`时间、给予`O(n · n!)`运营。 甚至`n=10`已经意味着大约 3600 万次基本日级操作，而`n=5000`使得该方法完全不可行。 

有用的观察是我们实际上并不关心第一个的确切顺序`k`概率。 任期内

 [
 q_1q_2\cdots q_k,
 ]

 仅第一个集合`k`要素很重要。 在均匀随机排列下，第一个`k`元素形成均匀随机`k`- 原始数组的元素子集。 

让`e_k`是基本对称度和`k`失败概率：

 [
 e_k =
 \sum_{1\le i_1<i_2<\cdots<i_k\le n}
 q_{i_1}q_{i_2}\cdots q_{i_k}。 
]

 正好有

 [
 \binom nk
 ]

 第一个的可能集合`k`位置，所有可能性均等。 因此

 \frac{e_k}{\binom nk}。 
]

 最终的答案是

 [
 \sum_{k=1}^{n}\frac{e_k}{\binom nk}。 
]

 初等对称和可以通过标准一维多项式 DP 来计算。 然而，存储`e_k`直接在数值上不方便，因为这些值可能大到`\binom nk`。 相反，我们在逐个处理概率的同时维护一个标准化版本。 

加工后`m`失败概率，定义

 [
 dp_k =
 \frac{e_k^{(m)}}{\binom mk},
 ]

 哪里`e_k^{(m)}`是学位-`k`这些的基本对称和`m`价值观。 每一个`dp_k`是数字乘积的平均值`[0,1]`，所以它也在于`[0,1]`。 

假设下一次失败的概率是`q`。 普通的初等对称递推是

 e_k^{(m-1)}+q e_{k-1}^{(m-1)}。 
]

 除以之后`\binom mk`，两项获得简单系数：

 \frac{m-k}{m}dp_k^{(m-1)}
 +
 \frac{k}{m}q,dp_{k-1}^{(m-1)}。 
]

 这给出了一个`O(n^2)`算法仅使用`O(n)`记忆。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(n · n!)`|`O(n)`| 太慢了|
 | 最佳 |`O(n²)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 转换每个成功概率`p_i`其故障概率`q_i = 1-p_i`。 预期的等待时间自然是通过连续的失败来表达的，因此这些就是 DP 需要的数量。 
2. 初始化`dp[0] = 1`和其他所有`dp[k] = 0`。 在处理任何概率之前，空乘积是`1`，而不存在正大小的子集。 
3. 一次处理一个失败概率。 假设当前处理值的数量是`m`。 对于每一个`k`从`m`下降到`1`, 更新

 \frac{(m-k)dp_k+kq_mdp_{k-1}}{m}。 
]

 循环必须向后进行，因为`dp[k-1]`仍必须引用先前处理值数量的状态。 更新转发会在使用之前覆盖该状态。 
4. 毕竟`n`概率已被处理，`dp[k]`等于

 [
 \frac{e_k}{\binom nk},
 ]

 这正是第一个故障概率的预期乘积`k`均匀随机排列的位置。 
5. 总和`dp[1]`通过`dp[n]`。 根据非负整数值等待时间的尾部求和公式，该总和就是 Jolany 等待的预期天数。 

### 为什么它有效

 加工后`m`值，不变的是`dp[k]`等于每个的平均乘积`k`-那些的元素子集`m`失败概率。 当新值`q`添加，一个`k`-元素子集要么排除`q`，在这种情况下它来自旧的`m-1`值，或包括`q`，在这种情况下它的另一个`k-1`元素来自旧的价值观。 有`m-k`相对于标准化平均值的第一类型的选择和`k`第二种类型代表的选择，恰好给出了上面的递归。 在`m=n`， 每一个`k`- 元素子集同样可能占据第一个`k`随机排列的位置。 因此`dp[k]`是所有第一个的预期概率`k`尝试失败。 将这些概率相加即可得出预期的等待时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(float, input().split()))

    # dp[k] = average product of all k-element subsets
    # among the probabilities processed so far.
    dp = [0.0] * (n + 1)
    dp[0] = 1.0

    m = 0
    for prob in p:
        q = 1.0 - prob
        m += 1
        inv_m = 1.0 / m

        # Descending order is required because dp[k - 1]
        # must still contain the previous-m state.
        for k in range(m, 0, -1):
            dp[k] = ((m - k) * dp[k] + k * q * dp[k - 1]) * inv_m

    answer = sum(dp[1:])
    print(f"{answer:.12f}")

if __name__ == "__main__":
    solve()
```数组`dp`存储归一化的基本对称和而不是原始和。 这避免了巨大的中间值。 例如，如果每个故障概率为`1`，原始 2500 度系数为`\binom{5000}{2500}`，它远远超出了普通浮点数的有用范围，而其归一化值只是`1`。 

外循环增加`m`从`1`到`n`。 此时，内循环会考虑第一个子集中可能存在的每个可能的子集大小`m`价值观。 降序是关键的实现细节。 例如，在计算新的`dp[3]`,`dp[2]`仍然必须是仅处理后获得的值`m-1`元素。 

表达式```
((m - k) * dp[k] + k * q * dp[k - 1]) * inv_m
```正是标准化的复发率。 使用`inv_m`避免对每个状态进行两次划分。 所有值均位于区间内`[0,1]`直至普通浮点舍入，因此不存在整数溢出，也不需要维护巨大的浮点系数。 

输入由单个测试用例组成。 该语句的实际输入格式以`n`，随后是`n`概率。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(n²)`| 对于`m`-th 概率，确切地说`m`DP 状态已更新，给出`1+2+...+n`运营。 |
 | 空间|`O(n)`| 仅一维`dp`数组和输入概率被存储。 |

 为了`n=5000`，DP 执行大约 1250 万次状态更新。 规范化表示使每个状态保持有界，因此普通的 Python 浮点算术足以满足所需的要求`10^-6`容错性。 这`O(n)`与 512 MB 限制相比，内存使用量很小。 规定的约束是`n <= 5000`。

 ## 边缘情况

 当机器有概率`0`，它总是失败。 对于输入```
1
0
```该算法转换`p=0`到`q=1`。 在`m=1,k=1`，更新给出`dp[1]=1`，所以答案是`1`。 DP 包括在可用天数内一直生存的概率，这正是仅成功计算会错过的部分。 

当机器有概率`1`，它总是成功的。 为了```
1
1
```失败概率为`q=0`。 唯一的状态变成`dp[1]=0`，给出答案`0`。 这也说明了为什么失败概率的乘积而不是成功概率的乘积是正确的数量。 

为了```
2
0 1
```失败概率是`1`和`0`。 在第一个值之后，`dp[1]=1`。 添加第二个值后，
 [
 dp_1=\frac{1\cdot+1\cdot 0\cdot 1}{2}=0.5,
 ]
 同时
 [
 dp_2=0。 
]
 答案是`0.5`。 这正是两个可能的订单的平均值，`[0,1]`和`[1,0]`，并确认 DP 对子集进行平均，而不假设位置之间的独立性。 

对于等概率，例如```
3
0.5 0.5 0.5
```排列不会改变任何东西。 失败概率总是`0.5`，所以预期的等待时间是

 [
 0.5+0.25+0.125=0.875。 
]

 DP 生产`dp[1]=0.5`,`dp[2]=0.25`， 和`dp[3]=0.125`，确认当所有值都相等时，归一化对称和会减少到普通幂。 

最后，当`n=5000`每个概率都是`0`， 每一个`q_i`是`1`。 每个子集产品也是`1`，所以每个归一化 DP 状态是`1`最终的答案是`5000`。 这是一个有用的压力案例，因为它达到了最大允许的年份长度，同时将数学上正确的答案保持在最大可能值。 归一化 DP 可以处理它，而无需构造原始初等对称和实现所需的巨大二项式系数。
