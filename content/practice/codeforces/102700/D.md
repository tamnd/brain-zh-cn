 ## 解决方案
 ## 问题理解

 我们有一系列相同的骰子。 单个骰子可以显示从 1 到 k 的所有数字，但能被 m 整除的数字除外。 所有允许的面都有相同的可能性，因此对最终总和唯一重要的是每个掷骰子模 m 的余数。 

任务是求 n 个独立掷骰的总和与 0 模 m 一致的概率。 答案不要求作为分数，而是作为模值。 如果概率是p/q，我们需要将p乘以q在模1000000007下的模逆。 

这些约束强烈地塑造了解决方案。 骰子的数量可以达到2 * 10^6，因此一一模拟骰子是不可能的。 边数也可以达到2 * 10^6，但m只有200。这告诉我们解应该取决于m而不是n或k。 O(nm) 左右的方法已经太大了，而 O(m^2 log n) 很容易管理，因为 m 很小。 

有几种边缘情况会破坏简单的实现。 如果 n = 1，则答案始终为零，因为单个骰子永远无法显示 m 的倍数。 例如，输入`1 6 3`有输出`0`，仅检查组合总数而不考虑缺失残基类的解决方案可能会失败。 

当 k 小于 m 时，会出现另一种微妙的情况。 例如，使用输入`2 2 5`，每个可能的面值都已经小于 m，但总和仍然可以是 m 的倍数。 可能的和是 2、3 和 4，所以答案是`0`。 假设每个残基都出现在面中的解决方案将产生不正确的分布。 

第三种情况是许多不同的面值塌陷为相同的残差。 有输入`2 6 3`，每个骰子可以是 1、2、4 或 5。残数并未均匀分布在所有可能的余数上，但最终答案是`1/2`，这变成`500000004`模 1000000007。将骰子视为残差上的均匀随机变量会给出错误的结果。 

## 方法

 直接的解决办法是维持当前和模m的概率分布。 对于一个骰子，我们计算每个余数有多少面产生。 然后我们将该分布与骰子分布重复卷积 n 次。 这是正确的，因为部分和所需的唯一信息是其模 m 的余数。 

问题是骰子的数量。 一个简单的动态编程解决方案将为每个芯片的每个余数执行 m 次转换，从而实现 O(nm^2) 操作。 当 n = 2 * 10^6 和 m = 200 时，这大约是 800 亿次操作，远远超出了限制。 

关键的观察是我们不需要数百万次应用相同的转换。 分布更新是循环卷积，相当于将x^m视为1时将多项式相乘。初始模具分布是具有m个系数的多项式。 将该多项式求 n 次方即可得出所有骰子掷完后的分布。 

因为多项式的次数总是以 x^m - 1 为模减少，所以每次乘法只需要 O(m^2) 的工作。 二进制求幂将乘法次数减少到 O(log n)，从而给出仅依赖于较小值 m 的算法。 

蛮力之所以有效，是因为它完全遵循概率转换，但当骰子数量变大时，它就会失败。 循环多项式表示保持相同的数学过程，同时允许使用幂运算跳过重复的转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nm^2) | O(米) | 太慢了|
 | 最佳 | O(m^2 log n) | O(m^2 log n) | O(米) | 已接受 |

 ## 算法演练

 1. 计算允许的面有多少个每个余数对 m 求模。 索引 r 处的值表示有多少条边产生余数 r。 余数 0 计数始终为零，因为这些边已被删除。 
2. 将此数组视为多项式，其中索引 r 是 x^r 的系数。 将两个这样的多项式相乘相当于将两个独立骰子的余数相加。 由于只有模 m 的余数很重要，因此每个指数都会模 m 约简。 
3. 使用二进制求幂将模具多项式求 n 次方。 从多项式 1 开始，它代表零个骰子和零之和。 每当设置 n 的当前位时，将答案多项式乘以当前幂多项式。 
4. 每次乘法后，进行循环卷积。 对于位置 i 和 j 处的两个系数，它们的贡献进入位置 (i + j) mod m，因为两个余数通过模加法组合。 
5. 求幂后索引 0 处的系数是其总和可被 m 整除的可能的掷骰序列的数量。 可能结果的总数为 s^n，其中 s 是一颗骰子上有效面的数量。 将系数乘以 s^n 的模逆，将计数转换为概率。 

工作原理：多项式不变量是指在处理任意数量的骰子后，系数 i 准确存储获得余数 i 的和的方法数。 乘法结合了两个独立的骰子组，并且减少模 m 的指数保留了总和的余数。 二进制求幂仅改变执行这些精确多项式乘法的顺序，因此余数为零的最终系数与直接滚动所有 n 个骰子相同。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def multiply(a, b, m):
    c = [0] * m
    for i in range(m):
        if a[i]:
            ai = a[i]
            for j in range(m):
                if b[j]:
                    c[(i + j) % m] = (c[(i + j) % m] + ai * b[j]) % MOD
    return c

def solve():
    n, k, m = map(int, input().split())

    cnt = [0] * m
    for x in range(1, k + 1):
        if x % m:
            cnt[x % m] += 1

    base = cnt
    result = [0] * m
    result[0] = 1

    while n:
        if n & 1:
            result = multiply(result, base, m)
        base = multiply(base, base, m)
        n >>= 1

    sides = k - k // m
    answer = result[0] * pow(sides, MOD - 2, MOD) % MOD
    print(answer)

if __name__ == "__main__":
    solve()
```这`multiply`功能是解决方案的核心。 它在 x^m = 1 定义的环中执行乘法，这就是每个目标索引使用的原因`(i + j) % m`。 数组总是恰好有 m 个元素，因此运行时间与 k 无关。 

初始系数数组是根据一个骰子的实际面构建的。 迭代所有 k 个面是安全的，因为 k 至多为 2 * 10^6，而后面的所有操作仅使用 m。 有效面数为`k - k // m`，因为 m 的倍数被精确删除。 

求幂循环遵循通常的平方乘法。 多项式存储在`base`代表两个骰子计数的幂，并且`result`累积所选的力量。 这些乘法的顺序不会改变最终的多项式，因为多项式乘法是结合的。 

最后的除法是通过模逆进行的。 分子已经以 MOD 模表示，分母是同等可能结果的数量，`sides^n`。 费马定理给出了逆矩阵，因为 MOD 是素数。 

## 工作示例

 对于输入：```
2 2 2
```每个骰子上唯一可能的面是 1。一个骰子的多项式是 x。 平方得到 x^2，它变成 1，因为指数取模 2。 

| 步骤| 当前多项式 | 结果多项式 |
 | --- | --- | --- |
 | 开始| [0, 1] | [1, 0] |
 | 使用 n | 的第一位 [0, 1] | [0, 1] |
 | 方形底座| [1, 0] | [0, 1] |

 余数为零的系数为1，并且只有一种可能的结果，因此概率为1。 

对于输入：```
3 2 2
```每个骰子仍然始终掷出 1。三个骰子的总和为 3，为奇数，因此答案为零。 

| 步骤| 当前多项式 | 结果多项式 |
 | --- | --- | --- |
 | 开始| [0, 1] | [1, 0] |
 | 使用第一位 | [0, 1] | [0, 1] |
 | 方形底座| [1, 0] | [0, 1] |
 | 使用下一位 | [1, 0] | [0, 1] |

 最终多项式在余数为零处没有系数。 该迹线证实求幂保留了精确的余数分布。

 ## 边缘情况

 对于`1 6 3`，算法创建分布`[0, 2, 2]`余数以 3 为模。乘以 1 求幂后保持不变，系数 0 仍为零。 最终的概率为零，这与一个已加载的骰子永远无法显示 3 的倍数这一事实相符。 

对于`2 2 5`，有效面值为 1 和 2。单模多项式仅在残数 1 和 2 处具有系数。将其与自身相乘会创建残数 2、3 和 4，但绝不会以 5 为模生成残数零。该算法返回零，而不假设每个残数均可到达。 

为了`2 6 3`，单模多项式为`[0, 2, 2]`。 将其平方即可得到残留物计数`[8, 8, 0]`循环卷积后。 总共有 16 个结果，其中 8 个产生残差为零，因此概率为二分之一，表示为`500000004`模 1000000007。相同的计算有效，因为多项式存储的是计数而不是概率。
