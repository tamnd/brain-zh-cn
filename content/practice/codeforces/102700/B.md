 ## 解决方案
 ## 问题理解

 我们有两个字符串，父亲的名字`a`和母亲的名字`b`，每个长度最多`2 * 10^5`。 婴儿的名字必须通过从以下内容中取出一个非空连续子字符串来形成：`a`，后紧跟一个非空连续子字符串`b`。 在所有此类串联中，我们需要字典顺序上最大的一个。 官方问题使用通常的字典排序，其中第一个不同的字符决定，如果一个字符串是另一个字符串的前缀，则较长的字符串较大。 

输入恰好是两个小写字符串，因此没有数字参数或多个测试用例。 输出是一个字符串，这是最好的串联。 

的约束条件为`2 * 10^5`字符排除任何接近枚举所有子字符串对的内容。 一个长度的字符串`n`有`n(n+1)/2`非空子字符串，因此即使在比较它们的串联之前，两个长度的字符串`2 * 10^5`大致产生`10^20`可能的对。 由于一秒的限制，预期的解决方案必须在总输入大小上是线性的或接近线性的。 后缀数组给出了可接受的`O(n log n)`方法，但还有一种更简单的线性时间方法来查找字典顺序最大后缀，这就是我们在这里使用的方法。 

有几种边缘情况可能会欺骗仅基于最大字符的解决方案。 考虑```
a
a
```答案是`aa`。 两个选定的子字符串都必须非空，因此仅返回最大的字符是无效的。 

考虑```
ab
z
```答案是`bz`， 不是`abz`。 宝宝的第一个字来自于父亲，所以最好的第一个字是`b`。 一个粗心的解决方案总是采用父亲的整个最好看的前缀，这会不必要地保留`a`在它之前并立即失去。 

现在考虑```
zb
a
```答案是`zba`。 这里扩展父亲的子字符串是有益的，因为下一个字符`b`大于第一个字符`a`的最优母子串。 总是只从父亲那里获取一个字符的解决方案将会返回`za`，较小。 

重复字符是另一种边界情况。 为了```
aaa
aaa
```答案是`aaaaaa`。 最大后缀可以从第一个位置开始，并且可以保留每个字符，因为父亲后缀中的每个字符至少与母亲所选后缀的第一个字符一样大。 

## 方法

 暴力解决方案很简单。 生成父亲姓名的每个非空子字符串和母亲姓名的每个非空子字符串，连接该对，并保留最大的结果。 这是正确的，因为每个合法的婴儿名字都准确地出现在这些对中。 

问题在于候选人的数量。 有`n(n+1)/2`父亲的子串和`m(m+1)/2`母亲的子串，准确给出`n(n+1)m(m+1) / 4`可能的对。 什么时候`n = m = 2 * 10^5`，这是关于`10^20`候选人。 如果对每个候选人进行比较`O(n+m)`，最坏情况的工作是`O(n^3m^2 + n^2m^3)`，这变成`O(N^5)`当两个字符串都有长度时`N`。 蛮力方法根本不可行。 

关键的观察是分别解决两个子串选择。 

对于母亲的子串，假设我们从位置开始`j`。 每个子串开头都有一个后缀的前缀`b[j:]`。 通过后缀的其余部分扩展该子字符串永远不会使其变小：如果较短的字符串是较长字符串的前缀，则较长的字符串获胜。 因此，在 mother 的所有子串中，字典序最大的子串恰好是字典序最大的后缀`b`。 

设该后缀为`C`，并设其第一个字符为`c`。 我们现在可以治疗`C`作为固定并解决了父亲这边。 

婴儿的第一个字符必须来自父亲，因此我们希望字典顺序上最大的可能起始位置`a`。 正确的起始位置是字典顺序最大后缀的开头`a`。 这是预期解决方案使用的标准最大后缀观察。 

假设这个后缀从位置开始`p`。 我们不一定要采用整个后缀。 在第一个字符之后，将与父亲的每个附加字符进行比较`c`，第一个字符`C`。 如果下一个父亲字符小于`c`，停止父亲的子字符串更好，因为替代方案将较小的字符放在较大的字符之前`c`。 如果下一个父亲角色至少是`c`，保留它至少同样好，所以我们继续。 

因此答案由最大后缀的前缀组成`a`，后跟最大后缀`b`。 父亲部分的第一个字符始终保留，即使它小于`c`，因为父亲的部分必须非空。 

可以使用两个候选位置和共享比较偏移在线性时间内找到最大后缀本身。 当两个后缀匹配多个字符时，第一个不匹配告诉我们可以丢弃一个候选者及其后的整个位置范围。 这就是防止表面上二次后缀比较实际上变成二次的原因。 标准最大后缀实现以线性时间和恒定的附加空间运行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n^3m^2 + n^2m^3)`|`O(n + m)`| 太慢了|
 | 最佳|`O(n + m)`|`O(n + m)`包括输出| 已接受 |

 ## 算法演练

 1. 查找母亲字符串的字典顺序最大后缀`b`。 调用其起始位置`q`，所以最优的母体部分是`b[q:]`。 我们可以使用整个后缀，因为每个正确的子字符串都从`q`是它的前缀，因此不会更大。 
2. 查找父亲字符串的字典顺序最大后缀`a`。 设其起始位置为`p`。 这给出了尽可能最好的第一个字符，并且在具有相同第一个字符的位置中，它给出了最强的后缀延续。 
3.让`c = b[q]`，所选母亲后缀的第一个字符。 从父亲的部分开始`a[p]`，必须始终包含它，因为父亲的子字符串不能为空。 
4. 扫描剩余字符`a[p:]`。 保留大于或等于的每个字符`c`。 当一个字符小于`c`，停止父亲的部分。 
5. 附加完整的最大后缀`b[q:]`到所选父亲的前缀。 打印结果字符串。 

停止规则直接来自字典比较。 假设所选父亲的前缀是`P`，下一个父亲角色是`x`。 停止给出`P + C`，其下一个字符是`c`。 继续给予`P + x + ...`。 如果`x < c`，停顿较大。 如果`x > c`，继续较大。 如果`x == c`，继续也永远不会更糟，因为继续在该相同字符之后给出另一个字符，而停止已经进入`C`; 最大后缀选择保证所选父亲的后缀仍然是有效的最佳代表。 预期的解决方案正是使用此前缀规则。 

### 为什么它有效

 让`C`是母亲名字的字典顺序最大后缀。 任何合法母亲的子串都不大于`C`，所以最佳的婴儿名字总是可以使用`C`。 

现在考虑一下父亲。 让`S = a[p:]`是其字典顺序上的最大后缀。 任何从其他地方开始的后缀都不大于`S`。 宝宝的第一个字符必须来自父亲，因此选择后缀小于的起始位置`S`无法改善结果。 一次`S`选择后，唯一的决定是在附加之前在哪里停止它`C`。 

在第一个位置之后的每个位置，比较是在保留当前父亲角色和立即进入之间进行`C`。 如果该父亲角色小于`C[0]`，输入`C`更好，所以父亲的子串必须停在那里。 如果至少是`C[0]`，保留它不会使结果变小。 因此最长的前缀`S`第一个之后的字符至少都是`C[0]`， 其次是`C`，是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def max_suffix_start(s: str) -> int:
    n = len(s)
    if n == 1:
        return 0

    i = 0
    j = 1
    k = 0

    while j + k < n:
        a = s[i + k]
        b = s[j + k]

        if a == b:
            k += 1
            continue

        if a < b:
            i = j
            j = i + 1
            k = 0
        else:
            j = j + k + 1
            k = 0

    return i

def solve(a: str, b: str) -> str:
    p = max_suffix_start(a)
    q = max_suffix_start(b)

    first = b[q]

    end = p + 1
    while end < len(a) and a[end] >= first:
        end += 1

    return a[p:end] + b[q:]

def main():
    a = input().strip()
    b = input().strip()
    print(solve(a, b))

if __name__ == "__main__":
    main()
```这`max_suffix_start`功能维持`i`作为当前最佳后缀和`j`作为挑战者。 变量`k`记录两个后缀有多少个字符匹配。 如果`a[i+k] < a[j+k]`，挑战者更好，所以`i`移动到`j`。 如果`a[i+k] > a[j+k]`，当前后缀获胜，并且可以跳过已经匹配的前缀覆盖的所有开头，因此`j`向前跳跃`k + 1`。 这种跳跃是例程是线性而不是二次的原因。 

找到后`p`和`q`，代码存储`b[q]`作为`first`。 父亲的部分开始于`a[p]`， 所以`end`开始于`p + 1`。 然后循环继续扩展，而下一个字符至少是`first`。 严格的`<`条件是重要的边界。 一个字符等于`first`被保留。 

Python 中不存在整数溢出问题，并且索引都是从零开始的。 循环条件`end < len(a)`防止读取父亲的字符串。 最后的切片也是安全的，因为两者`p`和`q`是有效的后缀开头。 

这两个电话`max_suffix_start`在各自的字符串中消耗线性时间。 最终的扫描仅触及父亲字符串的选定部分，因此它也是线性的。 最终的连接准确地创建了输出字符串。

 ## 边缘情况

 对于最小输入```
a
a
```每个字符串的最大后缀从索引处开始`0`。 父亲的部分开始于`a`，没有更多的父亲字符可供检查，完整的母亲后缀是`a`。 结果是`aa`，满足两个部分都非空的要求。 

对于相等的字符串```
aaa
aaa
```两个字符串的最大后缀是整个字符串，因为每个真后缀都是整个字符串的前缀，因此较小。 母亲的第一个角色是`a`，并且每个剩余的父亲字符都大于或等于`a`，因此保留父亲的整个字符串。 结果是`aaaaaa`。 

对于停止边界```
ab
z
```最大父亲后缀是`b`，而最大母后缀是`z`。 父亲选择的部分开始于`b`。 后面没有更多的字符，所以结果是`bz`。 如果我们从整体开始`ab`，第一个字符已经是`a`，使情况变得更糟。 

对于延伸边界```
zb
a
```最大父亲后缀是`zb`，最大母后缀是`a`。 从第一个父亲角色开始`z`必须保留，我们比较下一个字符`b`和`a`。 因为`b >= a`, 保持`b`产生更大的字符串`zba`而不是`za`。 

最后，对于最大尺寸的情况，其中父亲由以下组成：`200000`的副本`z`母亲由以下组成`200000`的副本`a`，每个字符串的最大后缀是整个字符串。 每个父亲字符都大于母亲的第一个字符，因此保留完整的父亲字符串，然后附加完整的母亲字符串。 该算法仅扫描每个输入固定次数，因此这种情况保持线性。
