 ## 解决方案
 ## 问题理解

 我们得到一串十进制数字。 对于任何数字，我们可以将其从当前位置删除，将其值增加 1（上限为 9），然后将结果数字插入字符串中的任何位置。 

该操作可以根据需要重复多次。 由于插入不受限制，因此数字的最终顺序很大程度上由我们控制。 挑战在于决定哪些数字应该增加和移动，哪些数字应该保持不变，以便结果字符串在字典顺序上尽可能小。 

所有测试用例的总长度最多为$2 \cdot 10^5$。 这立即排除了任何探索操作序列的方法。 甚至一个$O(n^2)$算法会有风险，因为单个测试用例可以包含$2 \cdot 10^5$数字。 我们需要每个测试用例接近线性的时间。 

棘手的部分是理解何时应该修改数字。 一个天真的想法是增加每个大数字，因为稍后移动它可能会有所帮助。 这并不总是正确的。 

考虑：```
s = 01
```答案是：```
01
```如果我们增加数字`0`，就变成`1`，产生更差的字符串。 

另一个微妙的情况是：```
s = 21
```答案是：```
13
```数字`2`出现在较小数字之前`1`。 保持`2`in place 强制最终字符串的第一个字符至少为`2`。 通过将其增加到`3`稍后移动它，我们允许`1`首先。 

第三个重要案例是：```
s = 999
```答案依然是：```
999
```尽管我们可能会重复应用运算，但数字的上限为`9`。 移动它们不能创建比现有的多组数字更小的任何东西。 

关键的观察是，只有当数字的右侧某处存在较小的数字时，该数字才会出现问题。 

## 方法

 蛮力观点是独立思考每个数字。 对于每个位置，我们可以决定是保留数字还是应用操作，然后尝试每个可能的插入位置。 这最终会生成所有可到达的字符串，并且按字典顺序最小的字符串将是答案。 

困难在于可能性的数量呈爆炸式增长。 即使决定保留或修改每个数字也已经创建了$2^n$可能性，插入位置增加了另一个组合因素。 这在很久以前就变得不可能了$n$甚至达到几十个字符。 

为了更快地找到某些东西，我们需要了解操作真正发生了什么变化。 

假设一个数字$s[i]$在其右侧某处有一个较小的数字。 然后无论我们以后做什么，保持$s[i]$那个较小的数字前面会损害字典顺序。 由于该操作允许我们删除$s[i]$，将其加一，然后将其放置在任何位置，我们应该这样做。 我们通过增加数字稍微牺牲了它，但我们释放了较小的数字以更早地出现。 

现在考虑一个已经小于或等于其右侧每个数字的数字。 这样的数字不会阻塞任何更小的值。 将其保留在原处至少与增加它一样好。 

这给出了一个干净的标准：

 对于每个位置，查看其右侧出现的最小数字。 如果存在严格较小的数字，则将当前数字增加 1（上限为 9）。 否则保持不变。 

做出这些决定后，确切的立场就不再重要了。 每个保留的数字都以其原始值保持可用。 每个修改的数字都会贡献其增加的价值。 由于移动的数字可以任意重新排序，因此只需对所有结果数字进行排序即可获得字典顺序最小的最终字符串。 

整个问题简化为计算后缀最小值并构建转换后的数字多重集。

 ## 算法演练

 1. 对于字符串$s$，计算每个后缀中出现的最小数字。 
2. 从左到右遍历字符串。 
3、对于职位$i$， 比较$s[i]$最小数字出现在其右侧的某个位置。 
4. 如果右边有更小的数字，则替换$s[i]$经过$\min(s[i]+1, 9)$。 
5. 否则保留$s[i]$不变。 
6. 将结果数字存储在列表中。 
7. 处理完所有位置后，对结果数字列表进行排序。 
8. 连接排序后的数字并打印结果。 

为什么排序有效？ 每个需要移动的数字都被转换为其增加的版本。 一旦所有这些决定都得到确定，该操作就允许将这些修改后的数字插入到任何地方。 多组数字按字典顺序排列的最小排列就是其排序顺序。 

### 为什么它有效

 仅当数字不大于其后的每个数字时，才应保持不变。 这样的数字永远不会阻止较小的数字更早出现，因此修改它不能改善最终字符串的前缀。 

如果右侧某处存在较小的数字，则保留当前数字之前的数字会使最终字符串以比必要的值更大的值开始。 将数字移开总是有利的，并且该操作需要支付恰好一个增量单位，上限为 9。 

因此，每个位置都有一个最佳局部决策，该决策仅取决于是否存在较小的后缀数字。 应用所有强制增加后，剩下的任务是排列所得的多组数字。 任何字典顺序最小排列都必须按非降序对数字进行排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        s = input().strip()
        n = len(s)

        suf_min = [''] * n
        suf_min[-1] = s[-1]

        for i in range(n - 2, -1, -1):
            suf_min[i] = min(s[i], suf_min[i + 1])

        res = []

        for i in range(n):
            if i + 1 < n and suf_min[i + 1] < s[i]:
                d = min(int(s[i]) + 1, 9)
                res.append(str(d))
            else:
                res.append(s[i])

        res.sort()
        print("".join(res))

solve()
```第一部分计算后缀最小值。 对于每个位置，我们想知道是否有更小的数字出现在后面。 后缀中从以下位置开始的最小值`i + 1`正好回答了这个问题。 

第二遍应用贪心规则。 如果最小的未来数字严格小于当前数字，我们将当前数字加一并将其标记为可移动。 否则我们保留它。 

确定所有转换后，只有结果数字的多重集才重要。 对它们进行排序会产生尽可能最小的字典顺序。 

最常见的实现错误是与包括当前位置在内的后缀的最小值进行比较。 我们特别需要`suf_min[i + 1]`，因为问题是右边是否存在更小的数字。 使用`suf_min[i]`会错误地将相同的数字视为存在较小数字的证据。 

另一个容易犯的错误是忘记了上限`9`。 当当前数字为`9`，增加它仍然剩下`9`。

 ## 边缘情况

 考虑：```
1
21
```右侧的最小后缀`2`是`1`，较小。 我们增加`2`到`3`。 数字`1`保持不变。 排序后，我们得到：```
13
```一个解决方案可以保持`2`会产生一个按字典顺序更大的字符串。 

现在考虑：```
1
01
```数字`0`其右侧没有更小的数字。 数字`1`已经是最后一个位置了。 不发生任何修改，并且排序保持不变：```
01
```这证实了我们不会修改数字，除非它们实际上阻止了更小的未来数字。 

最后考虑：```
1
999
```每个后缀最小值等于`9`。 没有位置会在其右侧看到严格较小的数字，因此每个数字都保持不变。 排序仍然会产生：```
999
```这验证了增量操作受到限制的边界条件，并且没有提供任何优势。
