 ## 解决方案
 ## 问题理解

 我们被排成一行，人们站在不同的坐标处。 每个人都有固定的位置，也有开始移动前的个人准备时间。 一旦选择了集合点，一个人的到达时间就是他们的准备时间和他们需要步行到该地点的距离的总和。 

目标是选择线路上的单个坐标，以便总到达时间最慢的人尽早到达。 换句话说，如果我们将人 i 的到达时间定义为`t_i + |x_i - x_0|`，我们想要选择`x_0`最小化这些值对所有人的最大值。 

这些限制表明所有测试用例的总人数最多为 200,000 人。 尝试每一个可能的相遇位置的简单方法是不可能的，因为答案空间是连续的并且很大，高达 10^8。 即使评估每个候选位置的函数也太慢了。 

一个微妙的点是，目标不是在固定索引上以简单的方式线性化，而是凸函数的最大值。 这意味着我们要最小化的函数本身是凸函数，但并非处处平滑。 

天真的直觉的一个常见失败案例是假设交汇点应该是头寸的中位数或某个加权平均值。 当准备时间不同时，这种情况就会立即中断。 例如，两个人处于相同的位置但不同`t_i`值可以将最佳交汇点完全移离该位置，因为成本不是纯粹的几何成本。 

另一个陷阱是尝试模拟移动或仅按位置排序。 准备时间就像每个“V 形”功能的垂直移动，这会改变哪个人占主导地位。 

## 方法

 如果我们确定候选人会议位置`x_0`，计算每个人的时间很简单：我们评估`t_i + |x_i - x_0|`并取最大值。 这给出了一个正确但昂贵的蛮力想法：扫描一组密集的候选位置并评估每个位置的最大成本。 

困难在于不能保证最优点位于任何输入坐标处，并且搜索空间是连续的。 尝试 0 到 10^8 之间的所有整数是不可能的，甚至评估每个点的函数也太慢了。 

关键的观察是我们正在最小化的函数是凸函数`x_0`。 每学期`t_i + |x_i - x_0|`是一个V形的凸函数，并且凸函数的最大值仍然是凸的。 直线上的凸函数具有唯一的全局最小值，可以使用三元搜索或通过检查其导数的符号来找到。 

然而，直接评估函数仍然是 O(n)，因此每次检查的成本为 O(n)。 通过大范围的三元搜索，我们只需要大约 60 次迭代即可收敛到足够的精度，使解决方案可行。 

另一种观点是从坡度的角度来思考。 当我们移动时`x_0`向右，一些人的贡献增加，而另一些人减少。 最佳点是“最严格的约束”从左侧贡献者主导转向右侧贡献者主导。 这个平衡点正是这些 V 形的最大值最小化的地方。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 整数暴力破解 | O(R·n) | O(1) | O(1) | 太慢了|
 | 凸函数的三元搜索 | O(n log R) | O(n log R) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 定义一个函数`f(x)`计算所有人到达某个点所需的最长时间`x`。 这是通过扫描所有人和计算来完成的`t_i + |x_i - x|`。 如果我们选择，该函数代表最坏情况的到达时间`x`。 
2. 观察`f(x)`在实数上是凸的。 这允许我们使用三元搜索来找到其最小值。 
3. 设置搜索间隔`[L, R]`最初覆盖所有可能的有意义的位置`[0, 1e8]`。 
4. 当区间仍然足够宽时，选取两个内点`m1`和`m2`，通常将片段分为三等分。 计算`f(m1)`和`f(m2)`。 
5. 如果`f(m1) > f(m2)`，最小值位于右侧，因此移位`L`到`m1`。 否则，转移`R`到`m2`。 这是可行的，因为凸函数先减小后增大，因此比较两个内点可以告诉我们哪一侧包含最小值。 
6. 经过足够的迭代后，将剩余区间的中点作为答案。 

这样做的原因是凸性确保存在一个全局最小值，并且两个点的每次比较都会消除无法包含它的区域。 该过程稳步缩小搜索间隔，而不会丢弃最优点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n = int(input())
        x = list(map(int, input().split()))
        tvals = list(map(int, input().split()))
        
        def f(pos):
            mx = 0
            for i in range(n):
                d = abs(x[i] - pos)
                val = tvals[i] + d
                if val > mx:
                    mx = val
            return mx
        
        l, r = 0.0, 100000000.0
        
        for _ in range(80):
            m1 = l + (r - l) / 3.0
            m2 = r - (r - l) / 3.0
            if f(m1) > f(m2):
                l = m1
            else:
                r = m2
        
        ans = (l + r) / 2.0
        print(ans)

if __name__ == "__main__":
    solve()
```功能`f(pos)`明确评估候选点的最大到达时间。 这是三元搜索使用的核心评估。 由于最佳点位于输入位置的凸包内，因此搜索间隔足够宽以覆盖所有可能的答案。 

80 次迭代的循环足以使间隔低于所需的精度。 每次迭代都会丢弃大约三分之一的剩余范围，因此即使对于高精度要求，收敛速度也很快。 

一个微妙的实现细节是直接使用浮点运算而不是尝试整数三元搜索。 由于所需的精度为`1e-6`，双精度就足够了。

 ## 边缘情况

 一个关键的边缘情况是所有位置都相同但准备时间不同。 例如，如果所有`x_i = 5`但`t_i`变化，最佳交汇点仍然是`5`，因为离开只会增加旅行时间，而不会减少任何准备工作。 该算法可以正确评估这一点，因为与 5 的任何偏差都会增加所有`|x_i - x|`平等地。 

另一个微妙的情况是，存在两个对立的群体，一个在左边，一个在右边，准备时间很长。 最佳点可能严格位于它们之间，而不是位于任何输入坐标处。 三元搜索自然会找到这个内部点，因为它不依赖于离散的候选点。 

最后，当只有一个人时，函数恰好在他们的位置上最小化。 评估函数简化为以`x_i`，并且最小值是微不足道的`x_i`，算法返回的结果没有不稳定。
