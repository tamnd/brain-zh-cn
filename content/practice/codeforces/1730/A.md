 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 在每个测试用例中都有多个整数集，其中每个整数代表行星的轨道标签。 具有相同值的行星属于同一轨道。 

我们有两种摧毁行星的方法。 一个选项以成本 1 移除一颗行星。另一种选项以成本 c 在一次操作中移除属于所选轨道的所有行星，无论该轨道上有多少行星。 

任务是选择这两种操作的组合，以消除所有行星，同时最小化总成本。 

输入的结构意味着只有不同轨道值的频率才重要，而不是它们的位置。 数组的任何排列都不会改变答案，因此问题简化为计算每个值的出现次数。 

约束很小，每个测​​试用例 n 最多 100 个，最多 100 个测试用例。 这意味着每个测试用例以 O(n²) 运行的任何解决方案都已经是安全的，但该结构允许更简单的线性计数方法。 

一个常见的失败案例来自于忽略频率聚合。 例如，如果所有行星都在不同的轨道上并且 c 很大，那么使用第二台机器是浪费的，但天真的贪婪方法可能仍然对每个行星应用一次。 相反，如果许多行星共享相同的轨道并且 c 很小，则无法将它们分组会导致重复使用第一台机器而付出过高的代价。 

一个小的说明性案例：

 输入：```
1
5 3
1 1 1 2 3
```如果我们单独销毁，成本是5。如果我们在轨道1上使用第二台机器，成本变成3 + 2 = 5。如果我们在所有轨道上使用它，成本变成3 + 3 + 3 = 9，这更糟糕。 正确的策略取决于比较每个轨道的节省，而不仅仅是原始计数。 

## 方法

 蛮力视角试图针对每个轨道子集决定是否使用第二台机器。 假设有 k 个不同的轨道。 对于每个轨道，我们选择支付该轨道的大小（重复使用第一台机器）或支付 c 一次（使用第二台机器）。 这导致 2^k 个选择。 计算每个选择的成本为 O(n)，因此总数变为 O(2^k n)，即使对于中等 k 也是不可行的。 

关键的观察是轨道是独立的。 对于频率为 f 的每个不同轨道值，我们仅比较两种成本：单独摧毁成本 f 和使用第二台机器成本 c。 不同轨道之间不存在相互作用，因为第二台机器不能部分破坏轨道。 

因此，最优决策是局部的：对于每个轨道，取 f 和 c 中的最小值。 将这些选择相加即可得出全局最优值。 

这将问题从组合选择简化为简单的频率聚合问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 轨道子集上的暴力破解 | O(2^k·n) | O(2^k·n) | O(k) | 太慢了|
 | 每个轨道的贪婪频率| O(n) | O(k) | 已接受 |

 ## 算法演练

 1. 读取轨道值数组并计算每个轨道有多少颗行星。 此步骤将问题压缩为独立的组，因为只计算物质。 
2. 对于每个不同的轨道，计算其频率 f。 这代表仅使用第一台机器摧毁该轨道上所有行星的成本。 
3. 对于该轨道，计算 f 和 c 之间更便宜的选项。 第二台机器只有在成本低于单独摧毁该轨道上的所有行星的情况下才有用。 
4. 将所有轨道上的这些最小值相加以获得总成本。 
5. 输出测试用例的结果。 

我们独立评估每个轨道的原因是轨道之间不存在共享利益：第二台机器一次不会影响多个轨道。 

### 为什么它有效

 每个轨道形成一个孤立的决策单元。 任何最优解决方案都可以进行转换，以便对于每个轨道，我们要么完全应用第二台机器一次，要么仅重复使用第一台机器，而不改变成本最优性。 在单个轨道内混合策略是不可能的，并且不存在跨轨道耦合，因此对每个轨道最优成本求和会产生全局最优解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        a = list(map(int, input().split()))
        
        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1
        
        ans = 0
        for f in freq.values():
            ans += min(f, c)
        
        print(ans)

if __name__ == "__main__":
    solve()
```解决方案首先使用字典按轨道对行星进行分组。 这确保我们只对频率进行推理，这是问题的正确抽象。 然后将每个频率与成本 c 进行独立比较。 

一个微妙的点是我们从不考虑部分使用第二台机器。 一旦选择了一个轨道，它总是会删除该轨道上的所有行星，因此分割其使用是没有意义的。 这就是 min(f, c) 比较完全捕获决策空间的原因。

def run(inp: str) -> str:

 ## 边缘情况

 一个重要的边缘情况是所有行星都属于同一个轨道并且 c 非常小。 

输入：```
1
6 2
5 5 5 5 5 5
```该算法计算频率 f = 6 并比较 min(6, 2)，得出 2。第二台机器占主导地位，因为它比单独删除更便宜。 

另一个边缘情况是每个轨道都是唯一的。 

输入：```
1
4 10
1 2 3 4
```每个频率为 1，因此每个轨道的 min(1, 10) = 1。 总数变为 4，正确地完全忽略了第二台机器。 

混合分布证实了独立性原则：

 输入：```
1
6 3
1 1 2 2 2 3
```频率为2、3、1。成本变为min(2,3)=2、min(3,3)=3、min(1,3)=1，总共6。每个轨道独立处理，决策过程中没有出现跨轨道耦合，证实了分解的正确性。
