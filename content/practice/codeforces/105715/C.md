 ## 解决方案
 ## 问题理解

 我们得到了一份不同商品价格的清单。 每个项目必须增加或保持不变，并且我们选择新的价格，以便最终系统恰好使用 k 个不同的值。 每件商品都会分配一个最终价格，并且该价格必须至少等于其原始价值。 目标是最小化所有项目的增加总量。 

思考这个问题的一个有用方法是，我们将原始价格“压缩”为 k 个级别。 每个项目都会四舍五入到这些级别之一，我们支付总的向上调整成本。 

这些约束允许所有测试用例总共最多包含约 2000 个项目，这立即排除了三次解。 每个测试用例接近 O(n^2) 的任何事情都是边界，但只有在仔细实施并且 n 的总和很小的情况下才可以接受。 任何显式尝试所有子集或分区的操作都会失败。 

当 k 等于 n 时，会出现一种微妙的边缘情况。 在这种情况下，我们可以保持所有值不同，因此最佳答案是零，因为我们可以简单地为所有 i 选择 e_i = s_i。 另一个极端，当 k 等于 1 时，所有项必须折叠成一个值，最佳选择是将所有项提升到最大元素，使成本 sum(max − s_i)。 如果没有明确地推理分组，以相同方式对待两个极端的幼稚方法将错过这些行为。 

另一个棘手的情况是当大值出现在数组的早期时。 由于我们只允许增加值，因此如果将小值分配给大目标，则不良的分组策略可能会迫使小值过度增加。 

## 方法

 暴力破解的想法是尝试所有可能的方法将数组分成 k 组并计算每个配置的成本。 对于固定组，如果其最大值为 M，则该组中的所有元素必须提高到至少 M，因此成本是该组上的 (M − s_i) 之和。 对所有组进行求和即可得到总成本。 

这是正确的，但立即变得不可行。 将 n 个元素划分为 k 个连续组的方法数量以 n 为指数，即使我们在排序后将自己限制为连续的段，直接的动态规划解决方案仍然会导致 O(n^2 k)，在最坏的情况下这太慢了。 

关键的观察结果是最终结构仅取决于排序。 由于所有操作都是单调增加，因此处理排序数组始终是最佳选择。 排序后，一个重要的结构事实就出现了：在最优解中，每个组对应一个连续的段，并且在每个段内，最终分配的值恰好是该段的最大元素。 

这将问题简化为选择 k 个分段来划分已排序的数组，从而最小化 (segment_size × segment_max −egment_sum) 分段的总和。 我们可以重新解释该过程，而不是直接优化分区：我们有效地选择 k 个“代表性”元素作为最终的不同值，并且每个元素都向上映射到不小于自身的最小代表。 

关键的简化是选择k个最大的元素作为代表是最优的。 一旦这些被修复，所有其他元素都会被推送到下一个选定的代表。 这种贪婪的结构消除了对分区动态编程的需要。

 ## 算法演练

1. 将原始价格数组按非降序排序。 这确保了最终值的任何有效分配都可以在向上舍入方面得到一致的解释。 
2. 选择最大的k个元素作为“代表值”。 这些将成为 k 个不同的最终价格。 直观上，较大的值更灵活，因为它们可以作为许多较小元素的目标，而不需要超出必要范围的额外增加。 
3. 对这k个代表按升序排序。 他们定义了一系列允许的最终级别。 
4. 对于每个原始元素，确定至少与其一样大的最小代表。 这表示元素将提升到的级别。 
5. 将所选代表与原始值之间的差值添加到答案中。 

由于两个列表都已排序，因此分配步骤自然是通过在代表之间移动的指针来实现的。 

### 为什么它有效

 不变的是，所选代表的集合在可行性方面始终主导任何最佳解决方案，并且绝不会不必要地增加成本。 任何最佳解决方案都必须具有 k 个不同的最终值，并且用较大的值替换集群内的任何非极大代表只会增加成本，而不会提高可行性。 因此，最优结构总是崩溃为选择 k 个最高有效目标并将所有内容贪婪地向上分配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        # choose k largest as representatives
        reps = a[n - k:]
        reps.sort()

        ans = 0
        j = 0

        for x in a:
            while j < k and reps[j] < x:
                j += 1
            ans += reps[j] - x

        print(ans)

if __name__ == "__main__":
    solve()
```该代码首先对数组进行排序，以便分组行为变得单调。 代表被取为 k 个最大的元素，这保证了恰好 k 个不同的最终值。 指针 j 确保每个元素都分配给最小的有效代表，从而避免不必要的增加。 

一个微妙的实现细节是 j 不会按元素重置； 它只会向前移动，因为两个数组都已排序。 这保证了排序后的线性扫描，防止 O(nk) 内循环。

 ## 边缘情况

 当 k 等于 n 时，每个元素都成为自己的组。 该算法通过选择所有元素作为代表来处理此问题，因此每个值都映射到自身并且成本保持为零。 

当k等于1时，代表集合仅包含最大元素。 所有其他元素都分配给这个单一值，产生的成本等于最大差值之和，这与所需的转换相匹配。 

当有许多小值和一些大值时，贪婪分配可确保将小值吸收到最小的可行代表中，避免将它们过度提高到不必要的大目标。
