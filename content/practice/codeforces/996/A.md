 ## 解决方案
 ## 问题理解

 我们得到一个整数，代表艾伦想要提取的总金额。 银行仅使用固定面额发放现金：1、5、10、20 和 100。任务是使用这些纸币面值准确表示给定金额，同时最大限度地减少所用纸币的总数。 

这不是任意硬币的分配问题。 面额集合是固定的且很小，我们被要求提供总和为目标值的最小件数。 每种面额均可无限次使用。 

输入约束允许金额高达十亿。 这立即排除了在值范围内的任何动态编程，因为即使是 n 的线性 DP 也需要多达 10^9 的状态，这是不可行的。 任何有效的解决方案都必须在恒定时间内有效。 

天真的尝试可能会尝试探索钞票的组合，例如尝试各种方法来选择每种面额的计数。 即使我们只考虑五种纸币的计数，对 100、20、10、5 和 1 种可能计数的暴力枚举很快就会变得无限制，因为 1 美元纸币的数量最多可达 10^9。 即使限制组合仍然会导致不切实际的搜索空间。 

当在较大面额之前过度使用较小面额时，就会出现微妙的边缘情况。 例如，当 100 张钞票出现时，使用过多的 20 会导致总计数减少，从而导致非最佳构造。 正确的解决方案必须避免局部次优选择。 

## 方法

 暴力方法会尝试总和等于 n 的所有可能的钞票组合，跟踪有效组合中钞票的最小数量。 从概念上讲，这是正确的，因为它枚举了整个解决方案空间。 然而，组合的数量随着 n 本身的增加而增加，因为 1 美元钞票的数量可以独立变化，最多可达 n。 即使我们按面额进行离散化，搜索空间也与最差维度中的 n/1 个选择成正比，导致每个状态的探索呈线性或更差。 这远远超出了 n 最多 10^9 的限制。 

关键的观察结果是，面额是在规范系统中构建的：每张较大的钞票都是较小钞票的倍数或接近倍数，并且在每一步贪婪地采取最大可能的钞票永远不会阻止最佳解决方案。 这是因为 100、20、10 和 5 是对齐的，因此用较小的钞票替换一张较大的钞票总是会增加钞票的数量。 例如，一张20美元的钞票总是比两张10美元的钞票好，一张10美元的钞票总是比两张5美元的钞票好，等等。 

这种结构将问题简化为从剩余金额中重复提取最大数量的高价值纸币，然后转移到下一个面额。 该过程变成了一个简单的整数除法序列。

 ## 算法演练

 我们按照从最大到最小的面额进行处理，始终提取尽可能多的当前面额的钞票。 

### 步骤

1. 从最大面额 100 开始，然后使用整数除法计算剩余金额中有多少张 100 美元钞票。 从金额中减去它们的总价值。 
2. 移至 20 美元钞票，并对其余钞票重复相同的操作。 此步骤是正确的，因为删除 100 秒后的任何剩余部分都严格小于 100，因此使用 20 秒在该缩小的范围内是局部最优的。 
3. 对 10 美元钞票重复同样的贪心提取。 
4. 对 5 美元钞票再次重复此操作。 
5. 最后，剩下的部分必须用 1 美元钞票支付，因此余数本身就是 1 美元钞票的数量。 

### 为什么它有效

 正确性来自于这样一个事实：每种面额都是以较小的纸币来表示其价值的最佳方式。 任何用较小钞票替换较大钞票的尝试仅在使用相同的替换物时严格增加或保留钞票数量，但永远不会提高计数。 这就形成了一种单调的结构：一旦我们拿走尽可能多的大钞票，以后的小钞票组合就无法弥补所用钞票总数的减少。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())

bills = [100, 20, 10, 5, 1]
ans = 0

for b in bills:
    ans += n // b
    n %= b

print(ans)
```该解决方案按面额降序迭代，并重复提取每个值的最大钞票数量。 变量`ans`累计已使用的账单总数。 每一步都减少`n`至无法用更高面额代表的剩余金额。 

处理顺序至关重要。 如果首先处理较小面额的钞票，即使可以减少总数量，也可能永远不会使用较大的钞票。 

整数除法和模运算在这里是安全的，因为所有值都保持在 Python 的整数范围内，并且不会发生精度问题。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(sys.stdin.readline().strip())
    bills = [100, 20, 10, 5, 1]
    ans = 0
    for b in bills:
        ans += n // b
        n %= b
    return str(ans)

# provided sample

# minimum input

# exact large denomination

# multiple of 20

 ## 边缘情况

 一个关键的边缘情况是当金额略低于大面额时，例如 n = 99。该算法采用零张 100 美元钞票，然后继续处理 20 美元钞票，产生四个 20 (80)，留下 19，然后是一张 10、一张 5 和四个 1。 总数为 4 + 1 + 1 + 4 = 10 张钞票。 任何强行发行 100 美元纸币的尝试都是无效的，而任何早期过度使用小面额纸币的尝试只会增加计数。 

另一种情况是，当 n 可以被大面额（例如 200）整除时。算法立即选择两张 100 美元的钞票并在没有余数的情况下终止，从而确认贪婪提取会产生严格的最佳表示，而不需要较小的钞票。
