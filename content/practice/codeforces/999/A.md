 ## 解决方案
 ## 问题理解

 我们得到一个从左到右按固定顺序排列的问题列表，其中每个问题都有一个难度值。 米什卡有一定的技能水平`k`，这意味着他只能解决难度不超过`k`。 

该过程受到一个重要的限制：在任何时刻，只有最左边和最右边的剩余问题可用。 米什卡反复选择这两个目的之一，消除这个问题，只有当它的难度在他的能力范围内时才解决它。 如果两个结局都无法解决，他会立即停止，并且无法采取进一步的行动。 

目标是确定他在陷入困境之前可以成功消除和解决多少问题。 

限制很小：`n ≤ 100`并且所有值最多是`100`。 这立即告诉我们，即使二次或三次模拟也很容易足够快，并且带有指针移动的贪婪模拟就足够了。 除了每步恒定时间检查之外，不需要高级数据结构或优化。 

一些边缘情况很重要：

 如果一开始两端都太困难，米什卡就解决不了任何问题。 例如，输入`n = 3, k = 1, [5, 6, 7]`产生输出`0`因为一开始就不存在有效的移动。 

如果所有值都在范围内`k`，无论选择如何，Mishka 最终都可以删除所有内容，因为每次删除都会不断暴露新的有效端点。 

一种微妙的情况是，每一步只有一侧有效，从而强制执行确定性序列。 天真的误解可能会尝试总是选择较小或较大的端点，但该问题不需要优化选择策略，因为任何继续删除可解端点直到被阻止的有效序列都会在这种贪婪约束下导致相同的最大删除数量。 

## 方法

 思考这个问题的一个直接方法是精确模拟该过程。 我们维护两个指针，一个位于数组的左端，一个位于数组的右端。 在每一步中，我们都会检查左值或右值是否可解。 

如果两者都无法解决，我们就停止。 否则，我们取有效端之一并将相应的指针向内移动，增加计数。 

因为两端总是可用的选择，所以自然的暴力想法是尝试所有可能的选择序列：在每一步，如果有效，则分支到向左或向右。 这导致了指数数量的状态，因为每个状态最多`n`步骤可以分为两个选择。 在最坏的情况下，这会变成`O(2^n)`，这是不必要的，因为该决策实际上并不以需要搜索的方式依赖于未来的结果。 

关键的观察是我们永远不需要走回头路。 一旦从任一端取出一个元素，它就会被永久删除，唯一的约束是它是否 ≤`k`。 就未来可行性而言，选择之间不存在使一个分支严格优于另一个分支的相互作用。 任何有效的移动对答案的贡献恰好为 1，只有当两端都无效时才会停止。 

这将问题简化为贪婪的双指针模拟：重复消耗有效端点，直到两端都不合格为止。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（尝试所有序列）| O(2^n) | O(2^n) | O(n) | 太慢了|
 | 两指针模拟 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们保留两个索引，`l = 0`和`r = n - 1`，和一个计数器`ans = 0`。 

1. 通过测试当前段的两端来检查进程是否可以继续。 
2.如果`a[l] <= k`, 通过递增删除左侧元素`l`并不断增加`ans`一个。 
3. Else if`a[r] <= k`，通过递减删除右边的元素`r`并不断增加`ans`。 
4. 如果两个条件都不成立，则立即终止，因为不可能进一步移动。 

每一步都与一次删除完全对应，因此循环将继续，直到该片段崩溃或变得无法播放。 

选择左优先背后的原因对于这个问题的正确性并不重要，因为每当两端都有效时，任何一个选择仍然保持过程一致：两个选择都消耗一个有效元素并将问题大小减少一个。 

### 为什么它有效

 在每一步中，唯一重要的因素是是否至少有一个端点是可解的。 If both endpoints exceed`k`，未来的任何操作都无法改变这种情况，因为如果不先删除端点，就无法访​​问内部元素。 因此，停止条件是全局有效的，而不是局部的。 每个有效的删除都会严格减少数组大小，同时保留剩余端点的正确性，因此该过程准确地模拟了可解删除的最大可能数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    l, r = 0, n - 1
    ans = 0
    
    while l <= r:
        if a[l] <= k:
            ans += 1
            l += 1
        elif a[r] <= k:
            ans += 1
            r -= 1
        else:
            break
    
    print(ans)

if __name__ == "__main__":
    solve()
```该实现使用经典的两指针模式。 循环条件`l <= r`确保我们只处理剩余的元素。 在内部，我们首先测试左端点，然后测试右端点。 这个顺序是任意的但一致的，因为两种选择对最终计数的贡献是相等的。 

当两个端点都无效时，终止条件被触发，这直接对应于问题陈述中的停止规则。 不需要额外的簿记。

 ## 边缘情况

 一个重要的边缘情况是第一个和最后一个元素都无效。 例如：

 输入：```
4 2
5 1 1 5
```一开始，两个端点都是`5`，这超过了`k`。 该算法检查两端，发现两者均无效，并立即停止并输出`0`。 

另一种情况是只有一侧有效：

 输入：```
5 3
3 4 4 4 3
```一步一步，左端始终先有效，直到无效，然后使用右端。 指针不断缩小，直到没有有效的端点剩余。 贪心规则仅在必要时正确地交替，并且从不跳过有效的移动。 

最后一种情况是完全可解的数组：

 输入：```
3 5
1 2 3
```该算法按顺序删除所有元素，因为在每一步中至少有一个端点有效，并且最终两个指针相遇。
