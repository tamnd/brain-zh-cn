 ## 解决方案
 ## 问题理解

 我们给定一个长度的字符串$n$其中每个位置都有一个可见的 ASCII 字符。 然后我们得到$m$操作，每个操作选择两个不同的字符$(x, y)$。 对于每个操作，规则是全局交换：每次出现$x$变成$y$，并且每次出现$y$变成$x$，同时穿过整个字符串。 这不是位置的局部交换，而是字符的完全重新标记。 

按顺序应用所有操作后，我们必须输出最终转换后的字符串。 

重要的限制是两者$n$和$m$可以大到$10^5$。 扫描每个操作的整个字符串的直接模拟将需要最多$10^5 \times 10^5 = 10^{10}$角色更新，远远超出了一秒的限制。 即使每个操作扫描一次字符串也已经太慢了。 

将交换解释为独立替换会产生一个微妙的陷阱。 交换是同时进行的，因此单个操作内的中间替换顺序不得泄漏到结果中。 例如，如果我们错误地替换了所有$x \to y$首先然后全部$y \to x$，除非我们仔细分离映射层，否则我们会破坏逻辑。 

另一个潜在的错误是重复重写字符串本身。 由于字符只改变身份，而不改变位置，因此我们不需要在每次操作期间直接修改字符串。 

## 方法

 蛮力的想法很简单。 对于每个操作$(x, y)$，我们扫描整个字符串并替换每个出现的$x$和$y$以及每一次出现$y$和$x$。 这正确地模拟了问题，因为每个操作都是统一应用的全局交换。 

问题是性能。 每次扫描都是$O(n)$，我们就这么做了$m$次，导致$O(nm)$。 和$10^5$在两个维度上，这都变得不可行。 

关键的观察是字符串本身在操作过程中不需要修改。 真正改变的是从原始字符到当前字符的映射。 每个操作仅更新两个符号之间的关系，而不是字符串中的位置。 

因此，我们不再重复接触字符串，而是维护一个映射数组，该数组告诉我们对于每个可能的 ASCII 字符，它当前代表什么。 最初，每个角色都映射到其自身。 当我们处理一个操作时$(x, y)$，我们交换图像$x$和$y$在这个映射里面。 在所有操作之后，我们将这个最终映射应用到原始字符串一次。 

这将问题简化为维护恒定大小的字母表（最多 94 个可见 ASCII 字符）的排列。 每次交换都是$O(1)$，最终重建为$O(n)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nm)$|$O(1)$| 太慢了|
 | 映射交换|$O(n + m)$|$O(1)$| 已接受 |

 ## 算法演练

 我们将每个字符视为表示 ASCII 值的固定大小数组中的索引。 核心思想是维护当前的身份映射，该映射随着每次操作而演变。 

1. 初始化一个映射数组，使每个字符映射到其自身。 这表示应用任何交换之前的身份转换。 
2. 对于每个操作$(x, y)$，将两个字符解释为索引并在映射数组内交换它们的映射值。 这模拟了应用全局交换而不触及字符串本身。 这样做的原因是我们正在跟踪标签的转换而不是字符串内容。 
3. 处理完所有操作后，通过迭代原始字符串中的每个字符并将其替换为其映射值来构造最终字符串。 
4. 输出构造结果。 

这样做的原因是映射数组始终表示由所有交换引起的字符的累积排列。 每个操作都是字符集上置换组的转置，组合这些转置相当于增量更新映射数组。 由于交换是全局且对称地应用的，因此不存在位置依赖性，并且每个原始符号的最终字符仅取决于最终排列，而不取决于中间状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    s = input().rstrip("\n")

    # visible ASCII range: 33 to 126 inclusive
    OFFSET = 33
    SIZE = 94

    mp = [i for i in range(SIZE)]

    for _ in range(m):
        x, y = input().split()
        xi = ord(x) - OFFSET
        yi = ord(y) - OFFSET
        mp[xi], mp[yi] = mp[yi], mp[xi]

    res = []
    for ch in s:
        idx = ord(ch) - OFFSET
        res.append(chr(mp[idx] + OFFSET))

    print("".join(res))

if __name__ == "__main__":
    solve()
```该解决方案干净地分离了关注点。 映射数组`mp`存储所有交换下每个角色的当前图像。 每个操作仅交换该数组中的两个条目，保留以下不变式：`mp[c]`是角色最终转变的身份`c`直到当前操作。 

最后的循环应用一次这种转换，确保我们只支付字符串长度的线性成本。

 -a→c

 ## 边缘情况

 一种边缘情况是多次交换形成循环。 例如，交换`a b`， 然后`b c`， 然后`c a`不会“破坏”任何东西； 它产生一个有效的排列。 该算法自然地处理这个问题，因为它只在映射数组中组成转置。 

输入：```
3 3
abc
a b
b c
c a
```逐步映射：

 - b 之后：a↔b
 - b c 之后：b↔c（因此形成循环）
 - c a 之后：完成循环

 最终映射将每个字符返回到旋转位置，产生一致的最终字符串。 实现从不依赖于字符串内的顺序，因此不会出现不一致。 

另一种边缘情况是字符串中未出现的字符参与交换。 由于映射数组包含整个 ASCII 范围，因此如果这些字符稍后出现或影响其他映射，这些操作仍然可以正确更新未来的行为。
