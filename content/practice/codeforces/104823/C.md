 ## 解决方案
 ## 问题理解

 我们得到一个由 32 个整数组成的固定大小数组，表示“扭曲”。 每个操作都描述了该数组上的受限就地转换。 该限制来自位掩码：只有其二进制表示形式包含掩码中设置的所有位的索引才允许参与操作。 具体来说，一个索引`p`如果每个位都设置，则处于活动状态`mask`也设置在`p`，这相当于条件`(p & mask) == mask`。 

然后，每个操作仅对活动索引执行三种结构化“并行复制和添加”行为之一。 在向上的版本中，每个活动位置`p`添加来自的值`p - delta`如果该源索引也处于活动状态。 在向下版本中，它添加了`p + delta`。 在异或版本中，它添加了`p ^ delta`。 所有更新都是同时进行的，这意味着每次添加都会在操作之前从原始数组状态读取。 

应用所有操作后，我们不输出最终的数组。 相反，我们计算所有 32 个元素的按位异或。 

就国家规模而言，限制非常小。 每个测试用例仅操作 32 个整数，最多 10 次运算。 即使有多达 1000 个测试用例，任何在 O(32) 时间内模拟每个操作的解决方案都非常快。 这立即排除了对跨测试用例的高级数据结构或优化的任何需要。 

主要的微妙之处是同时更新。 在迭代时就地更新数组的简单实现会损坏值，因为后续更新将读取已修改的条目。 正确的行为需要在每次操作之前拍摄阵列快照。 

第二个微妙的问题是掩模条件。 一个常见的错误是将掩码解释为相等`(p == mask)`而不是子集包含`(p & mask) == mask`，这会改变参与的索引并导致错误的传播。 

## 方法

 暴力模拟已经与问题的预期结构相匹配。 每个操作都是在 32 个索引上本地定义的，并且每次更新仅依赖于固定的小邻域（按 delta 移位或按 delta 异或）。 因此，除了单个操作步骤之外，不存在全局依赖性。 

简单的方法通过首先构建当前数组的副本来处理每个操作。 然后对于每个索引`p`从0到31，我们检查它是否满足掩码条件。 如果是，我们应用相应的规则：`up_add`，我们看`p - delta`， 为了`down_add`，我们看`p + delta`，并且对于`xor_add`，我们看`p ^ delta`。 如果源索引也处于活动状态，我们会将其值从快照添加到新数组中。 

这是可行的，因为每个操作都是在大小为 32 的常量域上进行的纯粹本地转换。它可能失败的唯一原因是就地更新，这是通过快照解决的。 

不存在需要消除的渐近瓶颈。 关键的见解是“扭曲”大小是固定的，因此模拟已经是最佳的。

 ## 算法演练

 我们维护一个 32 元素的数组`a`。 

对于每个测试用例，我们重复应用操作：

 1.将当前数组复制到临时数组中`b`。 此快照保留原始值，因此所有更新同时进行。 
2. 使用隐式计算活动索引集`(p & mask) == mask`。 
3. 对于每个索引`p`从0到31，检查是否处于活动状态。 如果不是，则在此操作中完全忽略它。 
4. 根据操作类型，计算目标源索引：

 1.如果`op == 0`， 放`q = p - delta`。 
2.如果`op == 1`， 放`q = p + delta`。 
3.如果`op == 2`， 放`q = p ^ delta`。 
5. 检查是否`q`是否在 0 到 31 范围内`q`在相同掩模条件下也有效。 如果两者都成立，则更新`b[p] += a[q]`。 
6.处理完所有索引后，替换`a`和`b`。 

完成所有操作后，计算中所有元素的异或`a`。 

这样做的原因是每个操作都定义了从旧数组到新数组的确定性转换，其中每次更新仅取决于先前的状态。 快照确保依赖项不会在单个操作中级联，从而保留预期的并行语义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def apply_op(a, op, mask, delta):
    b = a[:]  # snapshot

    for p in range(32):
        if (p & mask) != mask:
            continue

        if op == 0:
            q = p - delta
        elif op == 1:
            q = p + delta
        else:
            q = p ^ delta

        if 0 <= q < 32 and (q & mask) == mask:
            b[p] += a[q]

    return b

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n = int(input())
        a = list(map(int, input().split()))

        for _ in range(n):
            op, mask, delta = map(int, input().split())
            a = apply_op(a, op, mask, delta)

        x = 0
        for v in a:
            x ^= v
        out.append(str(x))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```核心实现细节是使用`a[:]`每次操作前。 如果没有这个，更新将泄漏到同一操作中的后续计算中，从而违反同时性。 

掩码检查出现两次：一次针对目标索引`p`，一次用于源索引`q`。 两者都是必需的，因为参与是按索引定义的，而不是按操作全局定义的。

 ## 边缘情况

 第一个边缘情况发生在`mask = 0`。 各项指标均满足`(p & 0) == 0`，因此该操作适用于所有位置。 这通常是隐藏的“压力情况”，其中传播变得全局而不是稀疏。 该算法可以自然地处理它，因为掩码检查始终为真，并且相同的模拟规则仍然适用。 

第二个边缘情况是`delta = 0`。 对于所有三个操作，源索引等于目标索引。 由于更新是附加的且同时进行的，因此每个活动位置的值每次操作都会增加一倍。 快照确保我们不会在同一操作中重复计数。 

第三种边缘情况是计算出的源索引`q`在向上/向下操作中超出范围。 这些贡献必须完全被忽略。 边界检查`0 <= q < 32`强制执行此操作，防止粗心实现可能引入的意外环绕行为。 

第四个边缘情况是异或连接。 即使当`p ^ delta`是有效的，它可能会不对称地违反掩码约束，这意味着逻辑对中只有一侧起作用。 该实现正确地要求两个端点都处于活动状态，确保不会有部分更新泄漏到非活动区域。
