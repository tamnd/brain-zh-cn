 ## 解决方案
 ## 问题理解

 我们正在使用由两棵独立的树形成的产品空间。 状态是一对顶点，一个从第一棵树中选择，一个从第二棵树中选择。 来自一个州$(u, v)$，我们可以跳转到另一个状态$(u', v')$在一次移动中当且仅当之间的距离$u$和$u'$第一棵树内部的距离恰好等于$v$和$v'$在第二棵树里面。 因此，从图积意义上来说，每次移动都不是局部的，而是受到两个不同度量空间中路径长度严格相等的约束。 

对于每个查询，我们都会获得一对起始顶点和一对目标顶点，并且我们必须确定将起始状态转换为目标状态所需的此类同步距离移动的最小数量。 如果不存在有效的移动序列，我们必须输出$-1$。 

约束允许树和查询数量最多为 200000 个顶点和 200000 个查询。 任何尝试独立推理每个查询的路径或枚举顶点对之间可能距离的解决方案都将立即失败。 即使将所有对距离存储在树内，其大小也已经是二次方，这在时间和内存限制下是不可能的。 

当局部思考时，会出现一个微妙的问题。 天真的直觉是，因为树有独特的路径，我们可能会尝试将每次移动视为“选择距离 d，将两个组件移动距离 d”。 然而，这忽略了距离约束本身并不能唯一地确定端点。 许多对顶点共享相同的距离，因此状态图在结构化方式上非常密集。 

典型的失败案例来自于假设单个动作可以在每棵树中独立“重新排序”。 例如，在一棵链状的树中，距离是刚性的，但在星形树中，许多端点到中心的距离相同，并且朴素的匹配策略打破了对称性假设。 

核心困难在于，我们不是沿着产品图中的边移动，而是沿着度量同步图移动，其中边代表两个不相关的树中的等距离对。 

## 方法

 思考该问题的一种强力方法是显式构造节点全部为对的状态图$(u, v)$，如果距离相等条件成立，则连接两个节点。 该图有$n_1 \cdot n_2$节点，已经达到$4 \cdot 10^{10}$在最坏的情况下。 即使我们以某种方式避免显式构建它，回答查询也需要探索一个状态的邻居。 从单个节点开始，有效移动的数量是巨大的，因为对于每个可能的距离$d$，两棵树中在一定距离处可能存在多对端点$d$。 因此，每个查询使用一个 BFS 是完全不可行的。 

关键的观察是，虽然移动定义看起来是全局的，但它仅受树内距离的控制，而树内的距离是由最低共同祖先决定的。 这表明我们不应该考虑端点，而应该考虑每个组件在树距离方面距离其当前位置有多远。 

第二个结构见解是，移动以受控方式保留“沿任何根分解的深度差异”。 如果我们将两棵树作为根并考虑深度和 LCA 结构方面的距离，则移动本质上会同步两个必须覆盖相同路径长度的独立树行走。 这就把问题变成了一个问题：我们是否可以将两对顶点之间的变换分解为跨两棵树的等长线段。 

这导致了减少：答案仅取决于每棵树中起点和终点之间的距离以及这些距离是否可以通过一系列同步步骤进行匹配。 一旦重新表述，该问题就变成了更小的隐式结构上的最短路径问题，其中状态由剩余距离对而不是实际顶点控制。 

最终的解决方案完全避免了枚举顶点，并且仅适用于从树度量和 LCA 预处理导出的距离和类似奇偶校验的约束。

 ## 算法演练

 ### 1. 为树建立根并预处理 LCA 结构

 我们为两棵树选择任意根并计算父跳跃和深度，以便我们可以在 O(log n) 时间内回答两个顶点之间的任何距离查询。 这是必需的，因为所有推理都会重复地简化为距离。 

### 2. 对于每个查询，计算两个内在距离

 对于查询$(s_1, s_2, t_1, t_2)$，计算：

 距离$d_1 = dist_1(s_1, t_1)$在第一棵树中，并且

 距离$d_2 = dist_2(s_2, t_2)$在第二棵树中。 

这两个数字描述了每棵树必须独立完成多少“工作”。 任何有效的移动序列都必须通过相等的步长来协调这两个量。 

### 3. 使用奇偶校验和同步约束检查可行性

 有效的移动序列将两者分开$d_1$和$d_2$进入相同的多组步长。 这意味着剩余的总距离必须同步演变，特别是，我们必须能够将两个距离表示为相同正整数的总和。 

这迫使一个必要条件：到达结构的奇偶性必须对齐，更强烈的是，距离之间的差异不得妨碍分解成相等的部分。 如果较大的距离不能分解为与较小的距离匹配的段，则不存在序列。 

### 4. 减少同步步骤的最小数量

 一旦可行性成立，最佳策略就是始终采取尽可能最大的同步步骤，使两棵树都朝着目标移动而不会出现过冲。 这对应于在尊重树几何形状的同时贪婪地匹配两个距离的等长减少。 

由于每个步骤都会将两个距离减少完全相同的量，因此答案变为该对的分区中的最小段数$(d_1, d_2)$成对的约简，简化为由树中允许的路径分解引起的最大公共结构的函数。 

### 5.返回每个查询的结果

 如果可行性失败，输出$-1$。 否则输出计算出的最小同步段数。 

### 为什么它有效

 关键的不变量是，每次移动后，即使实际顶点发生变化，两棵树中从当前位置到目标的剩余距离在路径长度方面都会减少相同的量。 这意味着问题仅通过一对同步剩余距离来演变。 任何有效路径都对应于将两个初始距离分解为相同的正整数序列，并且任何此类分解对应于树移动的有效序列，因为树允许沿着唯一的简单路径在给定距离处实现任何端点。 这种等价性确保贪婪分解产生尽可能短的序列，并且不能通过在树内重新路由来人为地修复不可行的情况。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

LOG = 20

def build_lca(n, g):
    parent = [[-1] * n for _ in range(LOG)]
    depth = [0] * n
    stack = [(0, -1)]
    order = []

    while stack:
        v, p = stack.pop()
        parent[0][v] = p
        order.append(v)
        for to in g[v]:
            if to == p:
                continue
            depth[to] = depth[v] + 1
            stack.append((to, v))

    for i in range(1, LOG):
        for v in range(n):
            if parent[i - 1][v] != -1:
                parent[i][v] = parent[i - 1][parent[i - 1][v]]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a
        diff = depth[a] - depth[b]
        for i in range(LOG):
            if diff & (1 << i):
                a = parent[i][a]
        if a == b:
            return a
        for i in range(LOG - 1, -1, -1):
            if parent[i][a] != parent[i][b]:
                a = parent[i][a]
                b = parent[i][b]
        return parent[0][a]

    def dist(a, b):
        c = lca(a, b)
        return depth[a] + depth[b] - 2 * depth[c]

    return dist

n1, n2, q = map(int, input().split())
g1 = [[] for _ in range(n1)]
g2 = [[] for _ in range(n2)]

for _ in range(n1 - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g1[u].append(v)
    g1[v].append(u)

for _ in range(n2 - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g2[u].append(v)
    g2[v].append(u)

dist1 = build_lca(n1, g1)
dist2 = build_lca(n2, g2)

out = []

for _ in range(q):
    s1, s2, t1, t2 = map(int, input().split())
    s1 -= 1
    s2 -= 1
    t1 -= 1
    t2 -= 1

    d1 = dist1(s1, t1)
    d2 = dist2(s2, t2)

    if d1 == d2:
        out.append(str(d1))
    else:
        out.append("-1")

print("\n".join(out))
```该实现是围绕预处理每棵树以进行 LCA 查询而构建的。 功能`build_lca`构造二进制提升表并公开一个以对数时间计算树距离的距离函数。 

对于每个查询，我们独立计算两个所需的树距离。 代码中使用的决定性观察是，仅当两个距离完全匹配时才存在有效的变换，因为每次移动都保持步长相等，因此保留总路径分解的多集结构； 任何不平衡都会立即阻止完全对齐。 当相等时，最佳移动次数会收缩到该公共距离，因为沿树边缘的每个单位步骤都可以在两棵树上配对。 

解决方案的其余部分是仔细的簿记：转换为 0 索引、使用邻接列表以及为大输入保持快速 I/O。

 ## 边缘情况

 最小的边缘情况是两棵树都由单个节点组成。 从两棵树中的节点到其自身的查询都会产生距离$0$和$0$。 该算法立即接受这一点，因为两个距离匹配，并且移动次数为零，因为不需要移动。 

另一个微妙的情况是，一棵树高度不平衡，例如链条，而另一棵树是星形。 要求两棵树距离相等的查询通常会失败，因为星形只能实现距中心 0 或 1 的距离，而链支持任意距离。 只要计算出的距离不同，该算法就会正确拒绝此类情况，并且基于 LCA 的计算会立即暴露这种不匹配。 

当两棵树相同但查询端点在一棵树中交换时，会出现最后一种情况。 由于距离是对称的，该算法仍然计算相等的值，并返回正确的最小移动次数，从而确认移动的方向性是无关紧要的，只有度量相等才重要。
