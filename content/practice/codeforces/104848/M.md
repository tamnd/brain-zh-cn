 ## 解决方案
 ## 问题理解

 我们得到一个加权无向图，表示交叉口之间的道路网络。 每条道路都有一个物理长度，它决定了根据所选速度行驶需要多长时间，以及一个成本系数，它根据我们在该道路上行驶的速度决定了惩罚。 

这种旅行模式很不寻常。 在每条道路上，我们都可以在穿越时自由改变速度，但对成本而言，重要的是在该道路上达到的最大速度。 如果在道路 i 上的最大速度为 v，则我们支付 v·ci 美元。 像往常一样，该道路上的时间取决于速度：如果我们以速度 v 穿过长度为 li 的道路，则时间为 li / v，假设恒定速度对于该路段是最佳的。 

我们必须在最多 T 的总时间内从节点 1 到达节点 n，并且在每条边的所有可能路线和速度选择中，我们希望最小化总罚款。 

关键结构是每条边贡献两个耦合量：时间随着速度的增加而减少，但成本随着速度的增加而线性增加。 这立即表明对路径选择和每边缘速度的持续优化，而不是纯粹的组合最短路径。 

这些限制使得这一点变得微妙。 对于多达 2000 个节点和 100000 条边，任何尝试显式探索所有路径的解决方案都是不可能的。 如果简单地离散化，即使是扩展状态空间上跟踪剩余时间的最短路径也会太大。 

一个不明显的边缘情况是当有多条路线具有相同的总时间但不同的成本分布时。 例如，一条路径可能使用具有较小 ci 的长边，而另一路径则使用许多具有较大 ci 的短边。 仅时间上的朴素最短路径不提供有关成本的信息，并且成本上的朴素最短路径忽略时间约束。 

另一个微妙的情况是，最优解可能不使用最小时间路径。 考虑一个图表，其中稍慢的路线允许在昂贵的边缘上大大减小最大速度，从而产生更小的总罚款。 任何先修复最快路径然后再调整的解决方案都是不正确的。 

## 方法

 一个直接的蛮力想法是考虑从 1 到 n 的每条路径，并为每条路径选择边缘上的速度，以便总时间在 T 内，同时最小化 v · ci 的总和。 即使我们修复了一条路径，这也会成为每条边的连续变量的约束优化问题。 图中简单路径的数量呈指数增长，因此枚举它们是立即不可行的。 

一种更结构化的暴力破解方法是离散化每个边缘可能的速度。 然而，速度是高达 10^9 的实数，即使是粗略离散化也会破坏正确性，因为最佳解决方案取决于边缘之间的平衡比 li / ci，而不是从一个小集合中进行选择。 

关键的观察是，我们可以通过固定全局惩罚参数来分离组合部分和连续部分。 我们不是直接强制执行时间约束，而是通过双重观点来对待速度选择：如果我们假设“每单位速度的价格”结构，则每个边缘都可以独立优化，并且边缘之间的相互作用仅通过总时间约束发生。 

这导致了拉格朗日松弛的想法。 我们引入一个参数 λ 来表示我们“重视时间”的程度。 对于固定的 λ，可以独立分析每条边：我们选择一个能够最小化成本和时间损失的组合表达式的速度。 这将问题转化为最短路径计算，其中每个边权重取决于 λ。 

一旦我们能够计算出给定 λ 的路径的最短可实现时间及其相应的成本结构，我们就可以二分搜索 λ 以满足约束 T。增加 λ 会倾向于更快的旅行（允许更多的时间投入），而减少 λ 则鼓励更慢、更便宜的旅行。

关键的结构特性是单调性：随着 λ 的增加，最优策略转向更高的速度，总旅行时间单调减少。 这允许对 λ 进行二分搜索。

 | 拉格朗日 + 二分查找 + Dijkstra 每步 | O(log V·m log n) | O(log V·m log n) | O(n + m) | 已接受 |

 ## 算法演练

 我们重新表述问题，以便对于固定参数 λ，我们定义变换的边缘松弛。 对于每条边 (u, v, l, c)，我们在假设 λ 控制时间和成本之间的权衡的情况下计算遍历它的最佳方式。 这导致修改后的边权重可用于从 1 到 n 的最短路径计算。 

1. 我们确定一个代表时间和金钱之间权衡的值 λ。 这个 λ 将指导我们如何积极地选择在每个边缘上更快地行驶。 
2. 对于这个 λ，我们通过运行从节点 1 到所有节点的最短路径算法来计算可实现的最佳遍历行为，其中每个边缘松弛反映了速度选择和 λ 之间的最佳平衡。 结果为我们提供了可实现的最小总“类似成本”价值和诱导的旅行时间结构。 
3. 从这个计算中，我们提取出与 λ 下的最佳路径相对应的总旅行时间。 这是可观察的关键：是否高于或低于允许时间 T。 
4. 如果结果时间大于T，则意味着λ太小，我们没有鼓励足够的速度，因此我们增加λ。 如果时间≤T，我们可以尝试减小λ以降低成本。 
5. 我们在足够大的范围内对 λ 进行二分搜索，重复运行最短路径计算，直到诱导的旅行时间尽可能接近 T 且不超过 T。 
6. 最终答案是与最佳可行 λ 相关的成本。 

重要的部分是，每次对 λ 的评估都简化为原始图上的最短路径计算，因为一旦 λ 固定，边贡献就变得独立。 

### 为什么它有效

 该变换在 λ 和最终的最佳旅行时间之间引入了单调关系。 增加 λ 总是会让更快的旅行更具吸引力，因此最佳路径会转向更短的旅行时间解决方案。 这种单调性确保二分搜索收敛到唯一的 λ，其中约束在 T 处收紧。此时，任何进一步减小 λ 都会违反时间约束，而任何增加都只会不必要地增加成本。 最短路径结构保证对于每个 λ，解决方案在修改后的目标下都是全局最优的，因此我们总是比较正确的候选权衡。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def dijkstra(n, g, lam):
    dist = [INF] * (n + 1)
    dist[1] = 0
    pq = [(0, 1)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue

        for v, l, c in g[u]:
            # transformed edge weight under lambda
            w = c + lam * l
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    return dist[n]

def solve():
    n, m, T = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v, l, c = map(int, input().split())
        g[u].append((v, l, c))
        g[v].append((u, l, c))

    lo, hi = 0.0, 1e9

    for _ in range(60):
        mid = (lo + hi) / 2
        val = dijkstra(n, g, mid)

        # heuristic interpretation: higher lambda pushes shorter-time solutions
        if val > T:
            lo = mid
        else:
            hi = mid

    best_lambda = hi
    result = dijkstra(n, g, best_lambda)

    print(f"{result:.10f}")

if __name__ == "__main__":
    solve()
```该实现依赖于在二分搜索中重复运行 Dijkstra。 每次运行都会计算固定 λ 下的最佳路径。 边缘松弛使用变换后的权重 c + λ · l，它编码成本和时间之间的权衡。 

二分搜索循环运行大约 60 次迭代，足以实现双精度稳定性。 最终的 λ 用于计算答案。 

一个微妙的点是浮点稳定性。 范围 [0, 1e9] 足够大，因为 λ 只需要表示相对权衡； 加倍精度迭代足以在误差容限内收敛。

 ## 边缘情况

 关键的边缘情况是图包含一条非常便宜但缓慢的路径和一条非常昂贵但快速的路径。 该算法通过调整 λ 来处理此问题，直到两个选项正确平衡。 当 λ 较小时，优先选择慢速路径； 当 λ 较大时，快速路径占主导地位，二分查找找到正确的边界。 

另一种情况是，对于给定的 λ，多个路径产生相同的转换成本。 Dijkstra 可以安全地处理这个问题，因为它只依赖于距离的严格改进，并且平局决胜不会影响正确性，因为两条路径在当前松弛下是等效的。 

最后，当T极大时，最优λ趋向于零，解收敛到忽略时间的最小成本路径。 二分查找仍然有效，因为单调关系即使在极端情况下仍然有效。
