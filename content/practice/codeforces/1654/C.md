 ## 解决方案
 ## 问题理解

 我们得到的最终权重为`n`蛋糕片。 这些块是通过重复选择一块重量从一个初始蛋糕生产出来的`w`并将其分为两部分：

 -`floor(w / 2)`-`ceil(w / 2)`确切地`n - 1`进行了这样的削减，导致`n`最后的作品。 最终作品的顺序并不重要。 

任务是确定给定的数组是否可能是某些有效分割序列的结果。 

一个有用的观察是，初始蛋糕重量没有明确给出，但它是强制的。 每次分割都会保留总重量，因此起始重量必须等于所有最终碎片的总重量。 

制约因素很大。 在所有测试用例中，总件数最多为`2 · 10^5`。 任何试图模拟所有可能的切割顺序的算法都会呈指数级增长。 甚至一个`O(n²)`在最坏的情况下，这种方法的成本太高。 我们需要一些接近的东西`O(n log n)`。 

一些边缘情况很容易被错误处理。 

考虑：```
1
3
2 3 3
```总和是`8`。 开始于`8`，唯一可能的第一次分裂是`4 + 4`。 继续这个过程永远不会产生精确的结果`{2,3,3}`。 正确答案是`NO`。 

另一个重要案例是：```
1
6
1 1 1 1 1 1
```答案是`YES`。 虽然每一个最终作品都是`1`，我们可以重复分割更大的碎片，直到出现六个。 每当看到许多相同值时就会停止的解决方案可能会错误地拒绝这种情况。 

第三个微妙的例子是：```
1
2
869 541
```总和是`1410`。 第一次分割必须是`705 + 705`。 双方都不相等`869`或者`541`，进一步分裂只会使碎片变得更小。 正确答案是`NO`。 

关键的挑战是确定一系列合法的分割是否可以准确地生成目标权重的多重集。 

## 方法

 强力方法将从总和开始，递归地尝试每个可能的分割序列，检查所得叶集之一是否等于目标多重集。 

这是正确的，因为它确实探索了每一个有效的结构。 不幸的是，可能分裂的树的数量呈指数级增长。 即使对于几十件，搜索也变得不可行，而这个问题允许最多`2 · 10^5`件。 

该操作的结构建议以相反的方式查看该过程。 

假设我们从初始蛋糕重量（即所有目标值的总和）开始，而不是询问是否可以从初始蛋糕中生产出目标块。 每当一个片段与所需值之一匹配时，我们就可以“消耗”它并停止分裂该分支。 

如果一个片段与任何剩余目标值都不匹配，则在转发过程中唯一可能发生的事情就是该片段被进一步分割。 由于分割已经完全确定，我们确切地知道如何继续：```
w -> floor(w/2), ceil(w/2)
```这导致了贪婪策略。 始终取当前可用的最大一块。 如果它与所需值匹配，则删除该要求。 否则将其分成两个孩子。 

为什么取最大的一块有意义？ 任何大于当前最大可用块的目标值以后都无法生成，因为分割只会减少权重。 尽早匹配大值可以避免因不必要的分割而浪费它们。 

我们可以按降序存储这两个多重集。 一个多重集包含目标值。 另一个包含反转过程时当前可用的部分。 

每当最大的可用块等于最大的所需值时，我们就会匹配它们。 否则我们就分割可用的部分。 

一个有用的修剪规则自然就会出现。 如果最大的可用块变得小于最大的所需目标，则不可能成功，因为未来的分割只会进一步降低值。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算目标数组的总和。 这是唯一可能的初始蛋糕重量。 
2. 将所有目标值存储在 max-struct 中。 在Python中，可以使用负值来模拟最大堆。 
3. 创建另一个仅包含总和的最大堆。 
4. 当两个堆都非空时重复此操作。 
5.让`x`是目前最大的一块并且`y`是最大的未匹配目标值。 
6. 如果`x == y`，将两者都删除。 这意味着我们已经成功识别了目标多重集的最后一块。 
7.如果`x < y`，立即返回`NO`。 最大的可用碎片已经太小了，未来的分裂只能使碎片变得更小。 
8. 如果`x > y`， 分裂`x`进入：```
floor(x/2)
ceil(x/2)
```并将这两个块插入回可用块堆中。 
9. 如果`x == 1`和`x > y`， 返回`NO`。 一块重量`1`无法进一步分割。 
10. 进程结束后，返回`YES`如果所有目标值都匹配，否则返回`NO`。 

### 为什么它有效

 不变的是，可用块的堆始终代表一组可能存在于从总和开始的有效切割过程的某个中间阶段的块。 

每当最大的可用部分等于最大的剩余目标值时，该部分最终必须在任何成功的构建中保持不变。 保留它并停止该分支上的进一步分裂不会损害有效的解决方案。 

当最大可用片段大于最大所需值时，该片段不能直接对应于任何剩余目标值，因此必须在每个有效构造中对其进行拆分。 分割是唯一确定的，没有其他选择。 

当最大可用块变得小于最大所需目标时，未来的操作不能增加其重量。 达到要求的值是不可能的，所以拒绝是正确的。 

这些观察强制贪婪过程的每一步，这意味着算法准确地接受可以通过合法切割产生的那些多重集。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        need = [-x for x in a]
        heapq.heapify(need)

        pieces = [-sum(a)]

        possible = True

        while need:
            if not pieces:
                possible = False
                break

            x = -heapq.heappop(pieces)
            y = -need[0]

            if x == y:
                heapq.heappop(need)
                continue

            if x < y:
                possible = False
                break

            if x == 1:
                possible = False
                break

            left = x // 2
            right = x - left

            heapq.heappush(pieces, -left)
            heapq.heappush(pieces, -right)

            if len(pieces) > len(need):
                possible = False
                break

        answers.append("YES" if possible else "NO")

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```第一个堆存储所有仍需要匹配的目标值。 第二个堆存储当前可用的块，同时反转构建过程。 

该算法重复比较每个堆的最大元素。 如果它们相等，我们就找到了最后一块并将其从考虑中删除。 

当可用块更大时，我们执行唯一合法的反向操作，将其分成可能在正向过程中产生它的两个块。 

条件`x == 1`很重要。 重量`1`无法进一步拆分，因此如果仍然不符合所需的值，则该实例是不可能的。 

支票```
if len(pieces) > len(need):
```是许多公认的解决方案中使用的有用优化。 一旦我们的可用棋子多于剩余的目标棋子，即使完美匹配也无法将棋子重新合并在一起，因此成功变得不可能。 

Python 整数可以轻松处理所有求和，因为最大总权重最多为：```
2 · 10^5 × 10^9 = 2 · 10^14
```它非常适合 Python 的任意精度整数。

 ## 边缘情况

 考虑：```
1
1
327
```总金额已经是`327`。 最大的可用块立即等于最大的目标块，因此算法匹配它并完成。 答案是`YES`。 假设至少需要一次拆分的解决方案在这里将失败。 

考虑：```
1
6
1 1 1 1 1 1
```该算法从`6`，反复分割较大的碎片，最终产生六个。 每一件都是单独匹配的。 由于重量`1`仅当它与目标值匹配时才被接受，该过程保持正确。 

考虑：```
1
2
869 541
```总和是`1410`。 分裂产生`705`和`705`。 之后，最大的可用块是`705`，而所需的最大块是`869`。 自从`705 < 869`，算法立即拒绝。 任何进一步分裂的序列都不可能将一块增加回`869`。 

考虑：```
1
3
2 2 2
```总和是`6`。 我们分成`3`和`3`，那么每个`3`进入`1`和`2`。 可用的部分变成`{2,2,1,1}`。 匹配两个目标二后，只剩下一个，而仍然需要目标二。 条件`x < y`检测到这一点并返回`NO`，这是正确的，因为使用允许的操作不能从重量为 6 的蛋糕中生成三个二。
