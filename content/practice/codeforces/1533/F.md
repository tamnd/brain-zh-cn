 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串。 对于固定值$k$，如果两个字符数中至少有一个很小，则认为子字符串有效：要么它最多包含$k$零或至多$k$那些。 

任务是将原始字符串分割成最少数量的连续有效片段。 我们必须计算每个的最小值$k$从$1$到$n$， 在哪里$n$是字符串的长度。 

长度可以达到$2 \cdot 10^5$。 任何处理每一个的解决方案$k$独立于$O(n)$时间已经成本$O(n^2)$，远远超出了极限。 总工作量必须接近$O(n \log n)$。 

一个微妙的一点是有效性并不基于长度。 如果一个字符足够稀有，那么长段仍然有效。 例如，与$k=1$, 段`0000001`有效，因为它只包含一个`1`。 

另一个容易犯的错误是一旦计数超过就切割$k$。 仅当两个计数都超过时该段才无效$k$。 为了$k=2$, 字符串`00011`仍然有效，因为它只有两个。 

当计算最大有效扩展时，会出现第三个陷阱。 认为$k=1$当前段从开头开始`00100010`。 最长的有效前缀不是由第一个超出限制的符号确定的。 一种字符类型可能已经超过$k$，而另一个仍保持在限制范围内，允许该段继续。 

## 方法

 暴力解决方案修复了一个值$k$，计算所有有效的段边界，并运行动态编程或贪婪分区。 即使我们在$O(n)$一个人的时间$k$，对所有人重复一遍$n$值给出$O(n^2)$， 大致$4 \cdot 10^{10}$最坏情况下的操作。 

关键的观察是对于固定的起始位置$i$，最长的有效段可以使用零和一的出现位置来描述。 

让：

-$p_0$是的位置$(k+1)$-st 零发生在或之后$i$。 
-$p_1$是的位置$(k+1)$-st 发生在或之后$i$。 

只要至少有一个计数最多仍然存在，段就保持有效$k$。 

如果我们之前停下来$p_0$，那么该段最多包含$k$零。 

如果我们之前停下来$p_1$，那么该段最多包含$k$那些。 

因此，最长的有效段在两个条件都失败之前立即结束。 它的下一个起始位置是$$\text{next}(i)=\max(p_0,p_1).$$一旦知道了这个跳跃函数，最佳分区就是贪婪的：总是采用最长的有效段。 任何较短的第一段只能减少未来的选择。 

剩下的挑战是计算所有人的答案$k$。 

对于小$k$，大约只有$\sqrt n$不同的价值观。 我们可以显式地为每个位置构建跳跃函数，并通过动态规划计算答案。 

对于大型$k$，每个段都很长，因此答案包含的段很少。 我们可以直接模拟贪心过程。 总成本比全部大$k$成为调和级数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(n)$| 太慢了 |
 | 最佳 |$O(n\sqrt n + n\log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 存储全0和全1的位置。 
2. 对于每个索引$i$，计算：

 - 前面出现了多少个零$i$,
 - 之前出现了多少个$i$。 

这些排名让我们直接跳到$(k+1)$-st 之后任一字符出现$i$。 
3. 选择阈值$B \approx \sqrt n$。 
4. 对于每一个$k \le B$:

 计算$$\text{next}[i] = \max( \text{pos0}[r_0(i)+k], \text{pos1}[r_1(i)+k] ),$$其中不存在的事件被视为位置$n+1$。 
5.对于同样的$k$, 计算$$dp[i]=1+dp[\text{next}[i]]$$从右到左。 

这里$dp[i]$是覆盖从以下位置开始的后缀所需的最小分段数$i$。 
6. 商店$dp[1]$作为这个问题的答案$k$。 
7. 对于每一个$k>B$，直接模拟贪婪分区。 

从位置开始$1$。 

反复跳转到$$\max( \text{pos0}[r_0(i)+k], \text{pos1}[r_1(i)+k] )$$直到位置变为$n+1$。 
8. 计算完成了多少次跳跃。 这个计数就是这个问题的答案$k$。 

### 为什么它有效

 对于开始于$i$，它变得无效的唯一方法是当它包含超过$k$零及以上$k$同时。 

零计数超过的第一时刻$k$是$(k+1)$-st 之后为零$i$。 计数超过第一个时刻$k$是$(k+1)$-st 后一$i$。 

在到达这两个位置之前，至少有一个字符数仍在限制之内。 在达到两个位置中较大的一个后，两个限制都被突破。 这唯一地确定了最长的有效段。 

贪婪地获取最长的有效段是最佳的，因为每个有效分区必须不晚于该点结束其第一个段。 尽可能扩展第一段永远不会增加未来片段的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    pos0 = [0]
    pos1 = [0]

    for i, c in enumerate(s, 1):
        if c == '0':
            pos0.append(i)
        else:
            pos1.append(i)

    zcnt = len(pos0) - 1
    ocnt = len(pos1) - 1

    pos0.extend([n + 1] * (n + 2))
    pos1.extend([n + 1] * (n + 2))

    r0 = [0] * (n + 2)
    r1 = [0] * (n + 2)

    z = o = 0
    for i in range(1, n + 1):
        r0[i] = z
        r1[i] = o
        if s[i - 1] == '0':
            z += 1
        else:
            o += 1

    r0[n + 1] = z
    r1[n + 1] = o

    B = int(n ** 0.5) + 1
    ans = [0] * (n + 1)

    nxt = [0] * (n + 2)
    dp = [0] * (n + 2)

    for k in range(1, min(B, n) + 1):
        for i in range(1, n + 1):
            p0 = pos0[r0[i] + k + 1]
            p1 = pos1[r1[i] + k + 1]
            nxt[i] = max(p0, p1)

        dp[n + 1] = 0
        for i in range(n, 0, -1):
            dp[i] = 1 + dp[nxt[i]]

        ans[k] = dp[1]

    for k in range(B + 1, n + 1):
        cur = 1
        cnt = 0

        while cur <= n:
            p0 = pos0[r0[cur] + k + 1]
            p1 = pos1[r1[cur] + k + 1]
            cur = max(p0, p1)
            cnt += 1

        ans[k] = cnt

    print(*ans[1:])

solve()
```数组`r0`和`r1`存储出现排名。 如果位置`i`是一个段的开始，那么`r0[i] + k + 1`指向第一个零，这将使零计数超过`k`。 同样的想法也适用于那些。 

对于较小的值`k`，我们显式构建跳跃图并使用一维 DP 计算最小段数。 由于每次跳跃都严格向右移动，因此 DP 是从右向左计算的。 

对于较大的值`k`，答案很小。 模拟贪婪跳转比构建完整的 DP 表更便宜。 

最常见的差一错误是出现查找。 我们需要$(k+1)$-st 出现在起始位置之后，对应于`rank + k + 1`。

 ## 边缘情况

 考虑`0101`和$k=1$。 整个字符串无效，因为它包含两个零和两个一。 粗心的实现可能会错误地允许它。 该算法找到第二个零和第二个，占据较大的位置，并在两个计数超过限制之前进行削减。 答案就变成了`2`。 

考虑`11111`。 每个子串都包含零个零，因此每个子串都是有效的，无论$k$。
