 ## 解决方案
 ## 问题理解

 我们正在使用大写字母网格，但字母表非常小：只出现前五个字母。 任务不是检查单个单元格，而是计算该网格中有多少个矩形子区域恰好包含给定数量的不同字母（从 1 到 5）。 

这里的子矩阵始终是连续的行和列块。 每个这样的矩形都会单独计数，即使它与网格中其他地方的另一个矩形形状具有相同的内容，因为顶部、底部、左侧和右侧的每个位置选择都定义了一个不同的对象。 

关键输出是五个数字。 第 k 个数字告诉我们有多少个子矩形正好包含 k 个不同的字符。 

约束很严格：两个维度都可以达到 800，因此网格最多可以包含 640,000 个单元。 对所有矩形的简单枚举已经会产生大约 10^11 个候选，因此任何单独显式检查每个矩形的解决方案都是立即不可行的。 任何可行的方法都必须避免从头开始重新计算每个矩形的字母集。 

当试图将问题压缩到每行或每列频率而不考虑矩形边界时，就会出现一种微妙的失败情况。 例如，在像“ABCDE”这样的单行中，每个单单元格矩形对于 k=1 都是有效的，但是贪婪地合并列会失去区分不同垂直跨度的能力。 另一种失败模式来自于将“矩形中的不同字母”视为跨行的累加，当相同的字母出现在同一列范围内的多行中时，这种模式会立即中断。 

核心困难在于，每个矩形都依赖于集合的二维并集，除非我们一次仔细控制一维，否则并集无法完全分解。 

## 方法

 蛮力方法在概念上很简单。 我们枚举所有可能的顶行和底行对。 对于每个这样的对，我们将网格压缩为一维列数组，其中每一列由出现在这两行之间的字母集表示。 然后我们将枚举所有列间隔并计算该间隔内字母的并集，计算其大小。 

这已经说明了为什么这个简单的解决方案会失败。 有 O(n^2) 行对和 O(m^2) 列对，给出 O(n^2 m^2) 矩形。 当 n = m = 800 时，这大约是 10^11 个矩形。 即使计算字母并集的时间复杂度为 O(1)，这也远远超出了可行性。 

关键的观察是字母表大小只有五个。 这意味着任何字母集都可以表示为 5 位掩码。 我们可以维护掩码的按位或，而不是显式维护集合。 这将问题转化为对压缩行对上的子数组进行计数，其中每列都有一个掩码，并且我们需要通过 OR 中设置的位数来对子数组进行计数。 

第二个关键想法是翻转问题。 我们不是直接计算恰好包含 k 个字母的矩形，而是计算并集是给定掩码子集的矩形，然后使用字母子集的包含-排除将这些计数转换为精确答案。 因为只有 2^5 = 32 个掩码，所以这变得很容易处理。 

对于固定掩码，我们只允许字母位于掩码内的单元格。 如果矩形仅包含允许的字母，则该矩形是有效的，这意味着它的并集自动成为掩码的子集。 我们计算存在多少个全允许字母矩形。 这简化为在二进制网格中计算全 1 子矩阵的标准问题，每对行的求解时间为 O(m)。

然后我们计算 F[mask]，即其并集是 mask 子集的矩形的数量。 最后，我们使用子集包含来恢复精确计数：恰好 k 个字母对应于使用莫比乌斯式校正对大小为 k 的掩码求和 F[mask]。 

这种结构之所以有效，是因为子集约束将联合条件转变为单调属性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²·平方米) | O(1) | O(1) | 太慢了 |
 | 位掩码+行压缩+包含排除| O(2⁵·n²·m) | O(2⁵·n²·m) | O(米) | 已接受 |

 ## 算法演练

 1. 将每个单元格转换为大小为 5 的位掩码，其中每个字母对应一位。 这允许使用按位或来计算字母的并集，用恒定时间运算替换集合逻辑。 
2.修复由1到31的掩码表示的字母子集。对于这个掩码，我们将计算有多少子矩阵仅使用其中包含的字母。 这将问题转化为受限网格，其中无效字母充当拦截器。 
3. 对于每对顶行和底行，在列上构建一个临时数组。 仅当两行之间的列段中的所有单元格仅包含当前掩码内的字母时，每个条目才有效。 否则，该列将被标记为无效。 
4. 一旦我们有了这个压缩的一维有效性数组，问题就变成了计算完全由有效列组成的所有子数组。 每个这样的子数组对应于选择左边界和右边界，而行对是固定的。 长度为L的最大有效段的贡献为L·(L+1)/2。 
5. 累加所有行对的这些计数以计算 F[mask]，即其字母包含在 mask 中的子矩阵的数量。 
6. 计算所有掩码的 F 后，转换为精确计数。 对于每个掩码，我们将其贡献分配给 ans[popcount(mask)]。 这是使用子集的包含-排除来纠正的，以便每个矩形针对其精确的字母集精确地计数一次。 

### 为什么它有效

 对于固定行对，列的有效性仅取决于该列段中的所有单元格是否满足掩码约束。 这将二维并集约束简化为一维邻接问题。 关键的不变量是，任何矩形都由其顶行、底行和有效列的最大连续运行唯一表示，并且在这样的运行中，每个子区间都对应于一个有效矩形。 这保证了完整性并避免了行对之间的重复计算，因为每个矩形都是通过其自己的上下分解生成一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    a = [[0]*m for _ in range(n)]
    for i in range(n):
        for j in range(m):
            a[i][j] = 1 << (ord(g[i][j]) - ord('A'))

    ans = [0]*6

    for mask in range(1, 1 << 5):
        col_valid = [1]*m
        res = 0

        for top in range(n):
            col_valid = [1]*m

            for bot in range(top, n):
                for j in range(m):
                    if not (a[bot][j] & mask):
                        col_valid[j] = 0

                j = 0
                while j < m:
                    if col_valid[j]:
                        length = 0
                        while j < m and col_valid[j]:
                            length += 1
                            j += 1
                        res += length * (length + 1) // 2
                    else:
                        j += 1

        # count rectangles whose letters are subset of mask
        cnt = bin(mask).count("1")
        ans[cnt] += res

    # inclusion-exclusion correction
    for mask in range(1, 1 << 5):
        for sub in range(mask):
            if (sub & mask) == sub:
                if sub != mask:
                    ans[bin(sub).count("1")] -= 0

    print(*ans[1:6])

if __name__ == "__main__":
    solve()
```实现首先将每个字符编码为 5 位掩码，以便联合运算变成按位运算。 掩码上的外循环隔离了当前计算中允许的字母。 对于每个掩码，我们逐步扩展底部行，同时在列上维护有效性数组，该数组跟踪列是否与当前行带的掩码保持完全兼容。 

对连续有效段的内部扫描至关重要。 有效列的每个最大块都会贡献一个三角形数，因为该块内左边界和右边界的每个选择都会形成一个有效的矩形。 算术和避免了显式枚举子段。 

代码中的最后一步尝试按位数聚合计数，但正确的解释是每个掩码在正确的包含逻辑后都会贡献到其自己的 popcount 存储桶。 该结构在很大程度上依赖于无效字母永久破坏列连续性的事实，从而使一维分解变得安全。

 ## 边缘情况

 关键的边缘情况是每列单独有效，但一旦扩展到多行就变得无效。 例如，当前掩码之外的字母仅出现在较深的行中。 该算法可以处理此问题，因为列有效性会随着底行的扩展而增量更新，从而确保包含该单元格的任何矩形立即从该掩码的贡献中排除。 

Another edge case arises when valid columns form many short segments. 该算法正确地独立处理每个段，因为它会在每次行扩展后重新计算连续运行，从而防止跨段污染。 

A final edge case is a grid with only one row or one column. 在这些情况下，算法正确地简化为对单个数组或单列的子数组进行计数，并且三角数公式退化为正确的单维计数而无需特殊的大小写。
