 ## 解决方案
 ## 问题理解

 我们得到了固定的字符串集合，所有字符串的长度都相同，并且要求我们回答有关稍长字符串的许多查询。 

每个存储的字符串都有长度$m$。 每个查询字符串都有长度$m+1$。 对于查询字符串$t$，我们想要计算有多少个原始字符串$s_i$可以变成$t$通过在某处插入一个字符$s_i$。 插入的字符可以进入任何位置，因此我们正在有效地检查是否从其中删除一个字符$t$可以生产$s_i$。 

所以每个查询都会问：在所有长度的字典字符串中$m$，有多少等于某个长度-$m$通过从查询字符串中删除一个字符而获得的子序列。 

这些约束立即决定了解决方案。 字符串和查询的数量都可以达到$10^5$，而每个字符串的长度最多为 10。最后一个细节是决定性的：虽然输入大小很大，但字符串非常短。 这表明任何解决方案都应该以允许恒定或接近恒定查询时间的方式预处理所有字符串，并且指数依赖于$m$是可以接受的，因为$m \le 10$。 

一种简单的方法是将每个查询与每个存储的字符串进行比较，并尝试删除每个可能的位置。 对于每对$(s_i, t)$，我们将检查是否删除一个字符$t$产量$s_i$。 那成本$O(m)$每张支票有$nq = 10^{10}$在最坏的情况下对，这太大了。 

如果我们尝试错误地“规范化”字符串，则会出现更微妙的问题。 例如，如果我们预先计算字符串的哈希值但忘记了删除位置的变化，我们可能会混淆不同的嵌入。 另一个陷阱是假设我们只能匹配前缀或后缀，但插入的字符可以出现在任何地方，因此仅按前缀/后缀严格分割是不够的，除非我们枚举分割位置。 

边缘情况很简单，但值得明确说明。 如果所有字符串都相同，则每个查询都会根据与该字符串匹配的删除位置数来计算所有匹配项。 如果查询包含重复的字母，则多个删除位置可能会产生相同的结果字符串，并且计数必须通过集合或散列频率图来避免重复计数。 

## 方法

 强力解决方案迭代每个字符串，并且对于每个查询，尝试从查询字符串中删除每个位置以形成候选字符串，然后检查该候选字符串是否存在于一组输入字符串中。 由于每个查询都有$m+1$可能的删除，每次检查都是$O(1)$使用哈希集进行平均，这将查询成本降低到$O(m)$。 然而，这忽略了匹配单个存储字符串的不同方式的多重性，更重要的是，它仍然需要仔细计算每个字符串，如果按对简单地实现，这会变得低效。 

关键的见解是扭转观点。 我们不是询问每个存储的字符串是否可以匹配查询，而是预先计算存储的字符串的所有“附近的超字符串”。 对于每个存储的字符串$s$，我们考虑向其中插入一个字符的所有可能方法。 这会产生一组长度$m+1$字符串，但显式枚举每个位置的所有 26 个选择会太大。 

相反，我们观察到一种更清晰的对称性：当且仅当从查询中删除一个位置产生存储的字符串时，查询才匹配存储的字符串。 因此，我们可以预处理哈希集中所有存储的字符串。 然后，对于每个查询，我们生成所有$m+1$删除一个字符得到的候选者，并统计该集合中存在多少个候选者。 

自从$m \le 10$，每个查询最多只需要11次子串检查，这是常数时间。 我们只需要确保当不同的删除产生相同的结果字符串时（当查询具有重复字符时会发生这种情况），重复项不会被计算两次。 每个查询的本地集解决了这个问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 成对暴力破解 |$O(nqm)$|$O(n)$| 太慢了 |
 | 删除枚举+哈希集|$O(nm + qm)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 读取所有存储的字符串并将它们插入到哈希集中。 

这允许在与生成的候选者进行比较时进行恒定时间的成员资格检查。 
2. 对于每个查询字符串$t$，初始化一个空的本地集来跟踪哪些候选结果已经被计算在内。 

当两个不同的删除位置产生相同的字符串时，这可以防止重复计数。 
3. 迭代每个索引$i$在查询字符串中$0$到$m$。 

对于每个索引，通过删除构建候选字符串$t[i]$。 

这对应于测试允许操作的逆操作。 
4. 如果该候选字符串存在于存储集中并且尚未针对该查询进行计数，则增加答案并将其标记为可见。 
5. 输出查询的最终计数。 

### 为什么它有效

 每个存储的字符串$s_i$可以出现在查询的答案中$t$当且仅当存在索引$t$其去除恰好产生$s_i$。 该算法明确列举了所有此类可能性。 因为每个有效匹配至少以一种方式对应于一个删除位置，并且在查询中过滤掉重复项，所以每个匹配都被计数一次且仅计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    st = set()

    for _ in range(n):
        st.add(input().strip())

    q = int(input())
    for _ in range(q):
        t = input().strip()
        seen = set()
        ans = 0

        for i in range(m + 1):
            cand = t[:i] + t[i+1:]
            if cand in st and cand not in seen:
                seen.add(cand)
                ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```该代码首先将所有字典字符串存储在哈希集中。 然后每个查询构造所有可能的长度 -$m$删除一个字符形成的字符串。 这`seen`set 确保重复删除产生相同的字符串不会使答案膨胀。 当查询包含重复字符时，这一点至关重要，因为不同的删除位置可能会产生相同的结果。 

切片操作`t[:i] + t[i+1:]`直接实现删除逻辑，并且由于$m \le 10$，其成本可以忽略不计。

 ## 边缘情况

 当查询包含重复字符时，会出现一种微妙的情况，例如`"aab"`。 删除第一个或第二个`'a'`产生相同的候选人`"ab"`。 没有一个`seen`设置，这会错误地多次计算相同的字典字符串。 

对于输入：```
1 2
ab
1
aab
```该算法处理删除：

 第一次删除给出`"ab"`，它在集合中，因此计数变为 1。第二次删除给出`"ab"`再次，但它已经被标记在`seen`，因此被忽略。 第三次删除给出`"aa"`，不在集合中。 最终答案正确的是1。 

即使多个删除位置折叠成同一个字符串，此行为也能保证正确性。
