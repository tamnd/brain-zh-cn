 ## 解决方案
 ## 问题理解

 维卡在固定日期抵达伯敦$k$。 她有几个朋友，每个朋友都会提供一段连续的时间，让她可以呆在他们的家里。 限制是她最多只能选择一个朋友，一旦选择，她就只能停留在该朋友允许的范围内。 然而，她不一定在该间隔开始时到达，因此她的实际停留时间必须不早于当天开始$k$。 

对于任何有间隔的选定朋友$[l_i, r_i]$，维卡只能从白天留下来$k$截至今日$r_i$，前提是$k$位于该区间内。 这意味着她的有效停留天数是$r_i - k + 1$，但前提是$l_i \le k \le r_i$。 如果没有区间包含$k$，她根本不能留下来。 

该任务简化为检查包含以下内容的所有间隔$k$并找到向右延伸最远的那个。 

限制很小：$t \le 500$,$n \le 100$，并且所有天的值都以 100 为界。这立即排除了对复杂预处理或高级数据结构的任何需要。 每个测试用例进行简单的线性扫描就足够了。 

当没有间隔包含时，会出现微妙的边缘情况$k$。 例如，如果$k = 4$所有间隔都像$[1,2]$,$[5,6]$，那么每个朋友要么开始太早，要么开始太晚。 在这种情况下，答案必须恰好是 0，因为维卡甚至不能停留一天。 

另一个边缘情况是当多个间隔包含$k$。 例如，$k = 3$和间隔$[1,4]$,$[2,6]$， 和$[3,3]$。 粗心的方法可能会选择最接近开始的间隔$k$，但这无关紧要。 正确的选择是右端点最大的区间。 

## 方法

 暴力解释是明确地模拟 Vika 的选择：对于每个朋友，检查是否$k$在于他们的间隔，计算如果她选择那个朋友她可以呆多少天，并取最大值。 这已经运行在$O(n)$每个测试用例，因为每个间隔检查一次。 

这里没有更深层次的组合结构，因为决策不依赖于间隔之间的重叠。 每个朋友都是独立的：他们可以在当天招待 Vika$k$或者他们不能。 一旦我们过滤了有效区间，最佳选择就仅由最大的右端点决定。 

更复杂的“优化”可能会尝试排序或扫描，但这会增加不必要的开销，而不会提高复杂性。 关键的观察是，唯一重要的约束是是否$k$在于$[l_i, r_i]$，并且在这些间隔中，最大化$r_i$直接最大化停留时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（检查所有间隔）|$O(n)$每个测试用例|$O(1)$| 已接受 |
 | 最优（同样思路，直接扫描） |$O(n)$每个测试用例|$O(1)$| 已接受 |

 ## 算法演练

 1. 对于每个测试用例，请阅读$n$和$k$，定义好友数量和 Vika 到达日期。 目标是根据这个固定参考点评估所有间隔$k$。 
2. 将答案变量初始化为 0。这代表 Vika 迄今为止可以停留的最佳天数。 从 0 开始自然可以处理不存在有效区间的情况。 
3. 迭代每个朋友的间隔$[l_i, r_i]$。 对于每个区间，首先检查是否包含天$k$， 意义$l_i \le k \le r_i$。 此条件确保维卡实际上可以在抵达当天开始在那里住宿。 
4. 如果间隔有效，则将潜在停留时间计算为$r_i - k + 1$。 这反映了当天入住$k$直到该时间间隔内的最后一天。 
5. 使用当前值和计算的停留长度中的最大值更新答案。 这确保我们始终在所有有效朋友中保留最佳选择。 
6. 处理完所有区间后，输出存储的最大值。 

### 为什么它有效

 该算法依赖于这样一个事实：Vika 永远不会早或迟离开所选朋友的时间间隔； 她的停留时间完全由开始日后的时间间隔右边界决定$k$是固定的。 每个有效区间都贡献一个独立的候选答案$r_i - k + 1$，并且无效间隔没有任何贡献。 由于决策空间是独立值的简单最大值，因此扫描所有间隔可以保持正确性，而不会丢失任何隐藏的交互。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
out = []

for _ in range(t):
    n, k = map(int, input().split())
    best = 0

    for _ in range(n):
        l, r = map(int, input().split())
        if l <= k <= r:
            best = max(best, r - k + 1)

    out.append(str(best))

print("\n".join(out))
```该解决方案为每个测试用例维护一个运行最大值。 条件`l <= k <= r`仅过滤可用的间隔，确保我们永远不会计算无效的停留时间。 表达式`r - k + 1`正确计算从到达到出发的包含天数。 

输出被缓冲以避免跨测试用例的重复 I/O 开销。

 ## 边缘情况

 当不包含区间时$k$，扫描永远不会更新初始答案 0。例如，$k = 7$, 间隔$[1,3]$和$[8,10]$都无效，因为都不满足$l \le k \le r$。 算法正确地将答案保留为 0 并直接输出。 

当多个区间包括$k$，只有正确的端点才重要。 例如，与$k = 3$, 间隔$[1,4]$,$[2,6]$， 和$[3,3]$，算法评估候选值$2$,$4$， 和$1$。 最大值为 4，来自$[2,6]$。 选择过程从不取决于间隔从左边多远开始，只取决于它从右边延伸多远$k$。
