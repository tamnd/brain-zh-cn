 ## 解决方案
 ## 问题理解

 宫殿是由房间组成的网格，每个房间都包含一个特定类型的箱子。 箱子按类型递增的顺序打开。 拍完胸型后`x`，里面的钥匙可以打开任何类型的箱子`x + 1`。 第一种类型的宝箱已经可用，最后的宝藏存放在唯一类型最大的宝箱中。 

任务是找到访问所需的箱子类型序列时所行驶的最小曼哈顿总距离。 如果当前宝箱类型有多个可能的位置，我们可以选择其中任何一个作为下一个目的地。 

输入给出了网格尺寸、箱子类型的数量以及每个房间中存储的类型。 输出是从起始房间到宝箱的最短步行距离。 

网格最多可包含 300 行和 300 列，即最多 90,000 个单元格。 尝试通过网格的所有可能路径的解决方案是不可能的，因为路径的数量呈指数增长。 当网格很大时，即使检查所有的单元对也已经变得太昂贵了，因为可能有数以万计的单元。 

有用的结构是两个房间之间的移动仅取决于它们的曼哈顿距离。 我们不需要模拟穿过网格。 我们只需要决定应该访问每种宝箱类型的哪个事件。 由于必须按顺序访问每种类型，因此该问题成为针对属于每种类型的位置组的动态规划问题。 

一些边缘情况可能会破坏更简单的解决方案。 

如果每种宝箱类型只出现一次，则无法选择路线。 例如：```
Input
1 3 3
1 2 3

Output
2
```该路径被强制从第 1 列到第 2 列，然后再到第 3 列。假设始终有多个选择的解决方案可能会错误地初始化转换。 

如果某个宝箱类型出现多次，贪婪地选择最近的出现位置可能会失败。 考虑：```
Input
2 3 3
1 2 1
1 3 1

Output
3
```贪婪的选择可能会进入 2 类箱子`(1,2)`，但正确的转换取决于所有类型 1 箱子的位置，因为在较大的示例中，先前的最佳位置可能会有所不同。 国家必须保留所有可能的立场。 

如果起始单元格已包含类型 1，则该位置的初始距离必须为零。 例如：```
Input
1 1 1
1

Output
0
```以非零初始成本开始的粗心实施将导致这个最小的情况失败。 

## 方法

 最直接的方法是在收集每种类型后保留所有可能的位置。 对于类型的每个位置`x`，我们计算该类型的所有位置中的最佳先前位置`x - 1`。 转换是正确的，因为键序列强制类型的顺序，因此过去需要的唯一信息是到达每个先前位置的最小成本。 

暴力实现遵循这个想法，但重新计算太多。 如果有`k`一种类型的位置和`t`下一个类型的位置，它执行`k * t`曼哈顿距离计算。 在最坏的情况下，多种类型可能出现多次，总功接近单元格数量的平方，大约`8 * 10^9`对于90,000个小区的网格来说，运行速度太慢了。 

关键的观察是细胞数量只有90,000个，但类型数量也可以很大。 我们需要利用这样一个事实：所有类型的头寸总数都是固定的。 最佳解决方案仍然执行动态编程转换，但仅在连续类型之间进行。 由于所有组中所有位置的总和就是单元的数量，因此当实现避免不必要的工作时，转换总数是可控的。 

对于每种类型，我们存储其坐标。 我们保持到达当前类型的每个坐标的最小成本。 然后我们使用这些值来计算下一个类型的成本。 包含最后一种类型的唯一单元格的最终值就是答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 最坏情况下的 O(n²m²) | O(纳米) | 太慢了|
 | 最佳| 直接公式中的 O(nmp)，受连续类型组之间的转换数量限制 | O(纳米) | 已接受 |

 ## 算法演练

 1. 存储按胸部类型分组的每个单元格位置。 一个类型可以出现在多个单元格中，因此我们需要一个坐标列表而不是单个坐标。 
2. 初始化类型的动态编程值`1`。 玩家开始于`(0, 0)`，因此到达类型 1 宝箱的成本是其距起点的曼哈顿距离。 
3. 处理箱子类型`2`到`p`。 对于当前类型的每个位置，尝试先前类型的所有位置并保留以下值的最小值：`cost of previous position + Manhattan distance between positions`这是过渡，因为玩家必须在到达当前类型的箱子之前已经打开了前一种类型的箱子。 
4. 将先前的动态编程数组替换为针对当前类型计算的值。 仅需要先前的类型，因此可以丢弃旧的状态。 
5、后处理类型`p`，输出宝箱的唯一存储值。 

为什么有效：后处理类型`x`，每种类型的动态规划值`x`位置表示收集完所有先前类型后到达那里所需的最小可能距离。 转换检查所有可能的先前类型`x - 1`职位，因此它会考虑达到新职位的所有合法方式。 采取最小值保留最佳路线。 通过对宝箱类型的归纳，最终状态包含到宝藏的最小距离。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, p = map(int, input().split())

    groups = [[] for _ in range(p + 1)]

    for i in range(n):
        row = list(map(int, input().split()))
        for j, x in enumerate(row):
            groups[x].append((i, j))

    INF = 10**18

    dp = []
    for r, c in groups[1]:
        dp.append((r, c, r + c))

    for typ in range(2, p + 1):
        ndp = []
        for r, c in groups[typ]:
            best = INF
            for pr, pc, val in dp:
                dist = abs(r - pr) + abs(c - pc) + val
                if dist < best:
                    best = dist
            ndp.append((r, c, best))
        dp = ndp

    print(dp[0][2])

if __name__ == "__main__":
    solve()
```这`groups`数组存储每种箱子类型的坐标。 这使存储的总位置等于单元格的数量，而不是创建一个由不必要的状态组成的大网格。 

初始动态编程状态是从类型 1 箱子构建的。 起点是`(0, 0)`，因此第一个移动成本就是到每个可能的类型 1 位置的曼哈顿距离。 

转换循环按升序处理类型。 对于每个新的胸部位置，内循环扫描先前类型的所有可到达位置并选择最小的总距离。 该代码将坐标及其当前最小成本存储在一起，因为下一次转换需要位置和累积距离。 

答案是`dp[0][2]`最后因为类型`p`保证只发生一次。 使用`10**18`防止溢出问题，并且大于网格中任何可能的路径长度。

 ## 边缘情况

 对于单细胞情况：```
Input
1 1 1
1

Output
0
```该算法创建一种成本为零的 1 类状态，因为箱子已经位于起始位置。 由于这也是宝物，所以最终储存的成本为零。 

对于重复类型的情况：```
Input
2 3 3
1 2 1
1 3 1

Output
3
```初始状态包含所有三个类型 1 位置及其距离`(0,0)`。 当处理类型 2 时，算法会检查每一种并保留最便宜的路线。 当转移到类型 3 时，也会发生同样的情况。它永远不会做出贪婪的局部选择，因此它会找到全局最短的序列。 

对于独特位置的情况：```
Input
1 3 3
1 2 3

Output
2
```每种类型都有一个坐标，因此每次转换都只有一个候选坐标。 该算法自然地简化为对强制曼哈顿距离求和。 

对于具有许多重复值的大网格，该算法仍然只保留一层成本。 它不存储所有可能的运动历史，因为前一个类型包含计算下一个类型所需的所有信息。
