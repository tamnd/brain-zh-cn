 ## 解决方案
 ## 问题理解

 给定一个小写字符串，我们需要找到同时满足三个条件的最长字符串。 

所选字符串必须是原始字符串的前缀、原始字符串的后缀，并且严格出现在字符串内部的某个位置。 内部出现不能使用整个前缀或整个后缀位置。 

例如，在`fixprefixsuffix`, 字符串`fix`出现在开头、结尾以及单词内部`prefix`，所以这是一个有效的答案。 

字符串长度可达一百万个字符。 这立即排除了任何二次方。 甚至一个`O(n^2)`算法需要大约`10^12`最坏情况下的操作，远远超出了两秒的时间。 我们需要一个线性或近线性的解决方案。 

棘手的部分不是检查字符串是否既是前缀又是后缀。 这可以通过标准字符串技术来完成。 真正的困难是验证相同的字符串也出现在中间的某个位置。 

一些边缘情况很容易被错误处理。 

考虑输入：```
aaaa
```正确答案是：```
aa
```前缀`aaa`也是一个后缀，但它并不严格出现在字符串内部。 它的两次出现恰好是前缀和后缀位置。 粗心的实现可能会错误地返回`aaa`。 

另一个危险的情况是：```
abcdabc
```前缀`abc`也是后缀，但没有中间出现。 正确的输出是：```
Just a legend
```仅检查前缀后缀相等性的实现在这里会失败。 

最小的情况也很重要：```
a
```非空子串不能同时是真前缀、真后缀和中间子串。 答案一定是：```
Just a legend
```重复的字符串会产生另一种微妙的情况：```
aaaaa
```正确答案是：```
aaa
```字符串`aaaa`既是前缀又是后缀，但同样它并不严格出现在内部。 我们必须区分重叠事件和有效的内部事件。 

## 方法

 蛮力方法很简单。 枚举字符串的每个可能的前缀。 对于每个前缀，检查它是否也是后缀以及它是否出现在中间的某个位置。 

假设字符串长度为`n`。 有`n`可能的前缀。 将前缀与后缀进行比较的成本高达`O(n)`，并且在字符串中搜索另一个匹配项的成本也高达`O(n)`。 总复杂度变为`O(n^2)`或者更糟，具体取决于搜索方法。 

和`n = 10^6`， 甚至`O(n^2)`是完全不可行的。 

关键的观察是问题只关心字符串的边界。 边框是一个既是前缀又是后缀的子字符串。 我们不需要测试所有子字符串，而只需检查边界。 

这自然就引出了 Knuth-Morris-Pratt 算法中的前缀函数。 前缀函数`pi[i]`存储字符串的最长正确前缀的长度，该前缀也是以位置结尾的后缀`i`。 

对于完整的字符串，`pi[n - 1]`给出最长的边界长度。 如果该边界也出现在前缀函数数组的较早位置，那么它出现在中间并且是有效答案。 

如果没有，我们可以使用前缀功能链接本身跳转到下一个较小的边界。 这是 KMP 的优雅部分：边界形成一条链。 我们不重新计算任何东西，而是在恒定时间内反复从一个边界移动到下一个较小的边界。 

这将问题转化为线性扫描加上一些边界跳跃，给出`O(n)`复杂。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算前缀函数数组`pi`对于整个字符串。 

前缀函数告诉我们，对于每个位置，以该位置结束的最长边界的长度。 
2.看`pi[n - 1]`。 

该值是最长前缀的长度，也是整个字符串的后缀。 
3. 记录最后一个位置之前出现的每个前缀函数值。 

我们只关心职位`0`通过`n - 2`因为最终位置对应于整个字符串后缀本身，而不是中间出现的位置。 
4.让`x = pi[n - 1]`。 

这是我们当前的候选答案长度。 
5. 虽然`x > 0`，检查是否`x`出现在前缀函数数组的较早位置。 

如果是，则长度前缀`x`发生在中间，所以我们找到了最长的有效答案。 
6.如果`x`没有出现较早，请使用以下命令移动到下一个较小的边框：```
x = pi[x - 1]
```这是有效的，因为边界的边界也是边界。 
7. 如果循环结束`x = 0`，不存在有效的子字符串。 

### 为什么它有效

 prefix 函数捕获字符串中的所有边界关系。 

每个有效答案都必须是完整字符串的边框，因此从`pi[n - 1]`保证我们从最长到最短的顺序审查候选人。 

如果边界长度出现在前缀函数数组中较早的位置，则意味着相同的前缀在某个内部位置结束，这证明子字符串出现在中间。 

过渡`x = pi[x - 1]`正确地移动到下一个可能的边界，因为完整字符串的任何较小的有效边界也必须是当前边界的边界。 

由于我们按降序检查边界，因此第一个有效的边界自动是最长的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    pi = [0] * n

    j = 0
    for i in range(1, n):
        while j > 0 and s[i] != s[j]:
            j = pi[j - 1]

        if s[i] == s[j]:
            j += 1

        pi[i] = j

    seen = [False] * (n + 1)

    for i in range(n - 1):
        seen[pi[i]] = True

    x = pi[n - 1]

    while x > 0:
        if seen[x]:
            print(s[:x])
            return
        x = pi[x - 1]

    print("Just a legend")

solve()
```第一部分在线性时间内计算 KMP 前缀函数。 

变量`j`存储当前匹配的前缀长度。 每当字符不匹配时，我们就会使用先前计算的前缀函数值向后跳转，而不是从零重新开始。 这就是 KMP 保持线性的原因。 

这`seen`数组记录了最终位置之前出现的边框长度。 使用布尔数组而不是集合可以避免对非常大的输入进行散列开销。 

搜索循环从整个字符串的最长边界开始。 如果该边框出现在内部，我们会立即打印它，因为我们正在按从最大到最小的顺序检查候选者。 

该行：```
x = pi[x - 1]
```是最重要的转变。 它遍历边界链而不重新计算任何东西。 

一个常见的错误是检查所有位置，包括`n - 1`填充时`seen`。 这将错误地接受仅作为完整后缀出现的边框。 

另一个常见的差一错误发生在`pi[x - 1]`。 prefix函数通过结束位置来存储信息，因此长度为前缀的边界`x`在索引处找到`x - 1`。

 ## 边缘情况

 考虑输入：```
aaaa
```前缀函数数组是：

 | 索引 | 人物 | 圆周率[i] |
 | ---| ---| ---|
 | 0 | 一个 | 0 |
 | 1 | 一个 | 1 |
 | 2 | 一个 | 2 |
 | 3 | 一个 | 3 |

 最长的边界有长度`3`，对应于`aaa`。 

我们检查是否`3`出现在最后一个位置之前。 事实并非如此。 该算法回落为：```
x = pi[2] = 2
```现在`2`确实出现得更早，所以答案变成`aa`。 

这可以正确拒绝仅作为前缀和后缀出现的边框。 

现在考虑：```
abcdabc
```最长边界长度为`3`，对应于`abc`。 

价值`3`永远不会出现在前缀函数数组中的最后一个位置之前，因此没有中间出现。 该算法回退到`0`并打印：```
Just a legend
```这可以防止错误地接受只出现两次的子字符串。 

最后，考虑：```
ababa
```最长的边界是`aba`， 长度`3`。 

该边界不会发生在内部。 该算法使用以下方法回退：```
x = pi[2] = 1
```现在边界`a`有效，因为它在字符串中出现多次。 

输出变为：```
a
```这个例子说明了为什么需要穿越边界链。 最长的边界可能会失败，而较小的边界仍然会成功。
