 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，对于每个位置，我们可以重复应用替换值的转换$x$和$-x-1$。 应用它两次会返回原始值，因此每个元素实际上只有两种可能的最终状态：本身或其转换后的版本。 

任务是为每个位置独立地选择两个可达值中的哪一个最终得到，以便所有最终数组值的乘积变得尽可能大。 然后我们输出任何达到该最大乘积的数组。 

约束条件$n \le 10^5$强制线性或近线性解。 任何涉及元素之间成对交互的操作，例如检查组合或全局模拟选择，都会立即变得太慢，因为即使$O(n^2)$已经是$10^{10}$运营。 

一些微妙的情况在这里很重要。 如果所有数字都是正数，则转换可能会产生负值，这会损害产品，因此我们希望避免它。 如果数字为负数，则将其转换为正数，从而显着改进产品。 零的行为很特别，因为它转变为$-1$，这对于乘法来说更糟糕，所以它通常应该保持不变。 主要困难在于产品优化通常需要全局平衡符号，这可能意味着决策之间存在耦合，但这里每个元素只有两个独立的状态，这简化了结构。 

## 方法

 蛮力方法会尝试每种选择的组合，将每个元素视为两者之间的二元决策$a_i$和$-a_i-1$。 这导致$2^n$可能的数组。 即使是为了$n = 30$，这变得不可行，并且在$n = 10^5$这是完全不可能的。 正确性是显而易见的，因为它枚举了所有可能性，但指数增长使其无法使用。 

关键的观察结果是，每个元素都可以在本地进行优化，而不会产生有害的全局相互作用。 这种转换是内卷的，这意味着每个值都有两个选项，除此之外没有其他结构。 我们比较每个索引的两个候选值：原始值$a_i$，以及变换后的值$-a_i - 1$。 令人惊讶的是，为每个索引独立选择这两个值中较大的一个就足够了。 

这样做的原因是所选值始终为非负值或最坏的为零，从而完全消除了符号冲突。 一旦所有数字都为非负数，最大化乘积就会减少为独立地最大化每个因子，因为增加任何单个因子都无法减少乘积。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n \cdot n)$|$O(n)$| 太慢了 |
 | 最佳|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 对于每个元素$a_i$，计算其变换后的值$b_i = -a_i - 1$。 这捕获了可到达的唯一替代状态$a_i$，所以我们完全枚举每个元素的决策空间。 
2. 比较$a_i$和$b_i$，然后选择较大的一个。 这确保了所选值始终是对最终产品的最佳本地贡献。 
3. 将所选值存储到结果数组中。 每个位置都是独立决定的，因此我们不需要重新审视之前的选择。 
4. 处理完所有元素后输出结果数组。 

### 为什么它有效

 每个元素恰好有两个可达值，选择这两个值中的最大值可以保证每个所选值都尽可能大。 该转换保留了索引之间的独立性，因此不存在将一个位置的选择与另一个位置的选择联系起来的约束。 一旦我们确保每个选定的值都是其对中较大的一个，最终的数组就按分量最大，并且由于在此选择规则之后所有选定的值都是非负的，因此增加任何单个元素只能增加或保留乘积。 这消除了对符号或奇偶校验进行全局优化的任何需要。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    res = []
    for x in a:
        y = -x - 1
        if x >= y:
            res.append(x)
        else:
            res.append(y)
    
    print(*res)

if __name__ == "__main__":
    solve()
```实现直接遵循每个索引都是独立的观察结果。 对于每个元素，我们计算其两种可能的状态并选择较大的一个。 该比较隐式处理所有边缘情况，包括负值、零和正数。 由于没有全局限制，因此不需要额外的簿记。

 ## 边缘情况

 关键的边缘情况是当值为$-1$。 在这种情况下，变换产生$0$，这对于产品来说绝对更好，因为零不会引入符号问题并且大于$-1$。 该算法正确地转换了每个$-1$进入$0$，这与最大化产品一致。 

另一个微妙的情况是零本身。 零转变为$-1$，无论是价值还是产品贡献都更差，因此算法保持不变。 这确保了零在最终产品中充当中性元素，而不是引入会降低整体结果的负面因素。
