 ## 解决方案
 ## 问题理解

 在无限平面上我们有两个圆族。 

第一个族包含以`(x, 0)`有半径`1, 2, ..., N`。 

第二个族包含以`(y, 0)`有半径`1, 2, ..., M`。 

所有圆都是同时绘制的，我们需要计算平面被分割成多少个连通区域。 

中心位于 x 轴上，因此每个圆对都水平对齐。 中心之间的距离是固定的：$$d = |x - y|$$这些约束立即排除了任何几何模拟。 两个都`N`和`M`可以达到`100000`，所以总的圆数可以是`200000`。 任何直接检查所有圆对的算法都需要大致`10^{10}`最坏情况下的比较，在 2 秒内是不可能的。 

问题的结构比原始几何更重要。 每个圆都属于两个同心族之一。 同一族内的圆永远不会彼此相交，因为它们具有相同的中心并具有不同的半径。 这样就只剩下来自不同家族的圈子之间的交集。 

棘手的部分是理解交叉点如何影响区域的数量。 

在圆相切的情况下，简单的实现通常会失败。 相切仅创建一个接触点，但不会分割任何现有区域。 

例如：```
1 0 1 2
```圆有半径`1`和中心距`2`，所以它们是外切线。 正确答案是`3`， 不是`4`。 

另一个危险的情况是内切线。```
3 0 1 2
```半径大的圆`3`和半径小的圆`1`满足：$$3 = 2 + 1$$同样，这些圆圈恰好在一点上相交。 触摸本身不会创建新区域。 

当一个圆完全位于另一个圆内而不接触时，就会发生第三种微妙的情况。```
5 0 1 1
```半径`1`圆心为`1`完全位于半径内`5`圆心为`0`。 它们根本不相交，因此较小的圆仍然独立地创建一个附加区域。 

许多错误的解决方案尝试只计算交叉点。 真正的不变量是每条新添加的曲线被之前的曲线切割成段的次数。 

## 方法

 蛮力的想法很简单。 对于来自不同族的每一对圆，确定它们是否相交于两点、一个点或根本不相交。 然后尝试重建平面图并应用欧拉公式。 

这在数学上是可行的，但实施很快就会变得混乱。 完整的平面图构造需要处理顶点、边、连通分量、相切和重复的交点。 更糟糕的是，检查所有`N * M`成对到达`10^{10}`最坏情况下的操作。 

关键的观察是我们实际上并不需要图表本身。 

当向平面添加新的简单闭合曲线时，区域数量增加：$$1 + \text{number of proper intersections with previous curves}$$切点不算在内，因为曲线未在此处分割。 

在一个家庭里，圆圈永远不会相交。 因此，唯一相关的事件是第一个家庭的一个圆和第二个家庭的一个圆之间的正确交集。 

两个有半径的圆`a`和`b`恰好在以下时间点相交于两点：$$|a - b| < d < a + b$$当等式成立时它们相切，否则不相交。 

每个适当的交点都会在新添加的圆上贡献两个交点，从而将其分割成额外的弧。 每个相交对都会增加区域计数`2`。 

我们从一个区域开始，每个圆至少再创建一个区域，即使它不相交。 

所以最终的公式就变成了：$$1 + (N + M) + 2 \times (\text{number of properly intersecting pairs})$$现在问题简化为计算对`(a, b)`满意：$$|a - b| < d < a + b$$和：$$1 \le a \le N$$

$$1 \le b \le M$$这可以通过算术范围来有效地计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(NM) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(N + M) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`N, x, M, y`。 
2. 计算中心之间的距离：$$d = |x - y|$$只有这个距离在几何上很重要。 

1. 初始化答案：$$1 + N + M$$该平面一开始是一个区域。 每个圆，即使没有交点，也会将一个现有区域一分为二。 

1. 计算正确相交的圆对。 

对于固定半径`a`从第一个家庭开始，我们需要所有半径`b`满意：$$|a - b| < d$$和$$d < a + b$$将它们重写为间隔界限`b`。 

从：$$|a - b| < d$$我们得到：$$a - d + 1 \le b \le a + d - 1$$从：$$d < a + b$$我们得到：$$b \ge d - a + 1$$结合一切：$$L = \max(1,\ a-d+1,\ d-a+1)$$

$$R = \min(M,\ a+d-1)$$每个整数`b`在`[L, R]`形成适当的交集对。 

1.添加：$$2 \times (R-L+1)$$每当得到答案`L <= R`。 

每个相交对都贡献两个额外的区域。 

1.输出最终答案。 

### 为什么它有效

 不变的是，每个新绘制的圆都会将区域数量增加到先前圆将其划分为的弧数。 

如果没有交点，圆就是一根连续的圆弧并添加一个区域。 

两个圆之间的适当交点会在每个圆上创建两个切点，从而增加圆弧数量`2`。 

相切不会将圆分割成额外的圆弧，因此它们不会改变增量。 

因为同一族内的圆永远不会相交，所以每个正确的交集都恰好来自相反族中的一对圆，并且每一对圆的贡献都完全相同`2`地区。 

这使得公式变得精确。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

N, x, M, y = map(int, input().split())

d = abs(x - y)

ans = 1 + N + M

for a in range(1, N + 1):
    L = max(1, a - d + 1, d - a + 1)
    R = min(M, a + d - 1)

    if L <= R:
        ans += 2 * (R - L + 1)

print(ans)
```实现直接遵循数学推导。`ans`开始于`1 + N + M`因为每个圆都至少贡献一个额外区域。 

对于每个半径`a`在第一个族中，代码计算半径的有效区间`b`来自产生适当交叉的第二个家庭。 

下限是三个约束中的最大值。 

第一个约束保持`b`积极的。 

第二个来自：$$a - b < d$$第三个来自：$$d < a + b$$上限来自：$$b - a < d$$还有`b <= M`。 

该区间包含在内。 如果`L <= R`，那么正好有：$$R - L + 1$$有效半径。 

每个有效对都会贡献两个新区域，因此我们将计数添加两倍。 

所有算术都很容易适合 64 位整数。 无论如何，Python 整数都是无界的。

import sys, io

def solve():
    input = sys.stdin.readline

    N, x, M, y = map(int, input().split())

    d = abs(x - y)

    ans = 1 + N + M

    for a in range(1, N + 1):

        R = min(M, a + d - 1)

def run(inp: str) -> str:

    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

 ## 边缘情况

 考虑外部相切：```
1 0 1 2
```中心距为`2`。 唯一有半径的圆对`(1,1)`。 

正确相交的条件是：$$|1-1| < 2 < 1+1$$变成：$$0 < 2 < 2$$第二个不等式失败了，因为相等意味着相切。 

该算法计算：

 | 一个 | 左 | 右 |
 | --- | --- | --- |
 | 1 | 2 | 1 |

 自从`L > R`，没有对被计数。 答案依然是：$$1 + 1 + 1 = 3$$现在考虑内切线：```
3 0 1 2
```这对`(3,1)`满足：$$3 = 2 + 1$$再次强调，平等意味着只接触一点。 

该算法排除了它，因为导出的不等式是严格的。 没有添加额外的区域。 

最后，考虑严格遏制：```
5 0 1 1
```半径`1`圆位于几个较大的圆内，但不与它们相交。 

该算法正确地计算了零相交对。 总计变为：$$1 + 5 + 1 = 7$$然后那对`(1,1)`正确相交，因为：$$0 < 1 < 2$$所以又添加了两个区域，给出`9`。 

几何形状与公式完全匹配。
