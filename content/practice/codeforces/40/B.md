 ## 解决方案
 ## 问题理解

 我们从一个`n × m`棋盘。 左上角的单元格是黑色的，因此颜色的交替与正常的棋盘完全相同。 只有最初的黑色单元格参与重绘过程。 

分钟`0`，每个黑色单元格都接收颜色`0`。 之后，分分钟`i`，我们重新绘制四个对角线邻居已经有颜色的每个黑色单元`i - 1`。 同一分钟的所有重新绘制都是同时进行的。 

在此过程中，单元格可能会被重新绘制多次。 任务是准确计算有多少个单元格被重新绘制`x`次。 

板的尺寸最多为`5000 × 5000`，这意味着细胞总数可以达到`25,000,000`。 对整个电路板进行多次迭代的任何模拟都是不可能的。 在这种规模的 Python 中，即使是单个全网格 BFS 风格的进程也已经很昂贵了。 价值`x`可以大到`10^9`，这完全排除了逐分钟的模拟。 

真正的挑战是理解重画规则在几何上的实际含义。 

当其中一个维度等于时，会出现微妙的边缘情况`1`。 

例如：```
1 5
1
```正确答案是：```
3
```最初有三个黑色单元，并且它们都没有四个对角邻居，因此该过程立即停止。 每个单元格在几分钟内只被绘制一次`0`。 

粗心的实现可能会尝试无限期地缩小层，并意外地产生负尺寸或计数不存在的单元。 

另一个棘手的情况是当`x`大于每个可能的重绘次数。 

例子：```
3 3
2
```正确答案是：```
0
```中心黑色单元被绘制两次，但角落黑色单元仅被绘制一次。 没有细胞能够存活足够长的时间来进行第三次重新粉刷。 

天真的模拟可能会错误地认为重新绘制会永远持续下去，因为声明说“无限”，但经过足够的步骤后，该过程稳定下来，并且没有更多的单元格符合条件。 

尺寸均匀的电路板也需要小心处理，因为黑色单元的数量不对称。 

例子：```
2 3
1
```黑色细胞是：```
B W B
W B W
```只有三个细胞参与。 答案是`3`， 不是`4`。 

棋盘的奇偶结构在整个解决方案中都很重要。 

## 方法

 最直接的想法就是模拟一分钟一分钟的过程。 

我们可以存储每个黑色单元的当前重绘计数并重复扫描板。 在每次迭代期间，我们检查所有四个对角邻居是否在前一分钟被重新绘制。 如果是，当前单元格也会被重新绘制。 

这个模拟是正确的，因为它完全遵循了陈述。 问题是成本。 层数可以大到大约`min(n, m) / 2`，每次迭代都会扫描整个板。 尺寸可达`5000`，这就变成了几千万或几亿的操作，这在Python中已经很不舒服了。 更重要的是，电路板本身可能包含 2500 万个单元，因此即使存储大型辅助结构也会变得昂贵。 

关键的观察结果是，重新绘制的行为与从边框剥落图层完全相同。 

仅当所有四个对角邻居都存在并且在上一步中也幸存下来时，黑色单元才能再次重新绘制。 这意味着单元格不能位于任何边界附近。 重新绘制一次后，最外层的对角线层就会消失。 再次重新绘制后，下一层就会消失，依此类推。 

因此，黑色单元格被重新绘制的次数仅取决于其到边界的最小对角线距离。 

我们可以直接计算每个对角线层有多少个黑色单元，而不是模拟该过程。 

假设一个单元格通过重绘而存活下来`x - 1`。 那么它至少必须是`x - 1`远离每一个边界，无论是垂直还是水平。 删除这些层会留下一个内部矩形：```
(n - 2(x - 1)) × (m - 2(x - 1))
```该矩形内的每个黑色单元格至少被重新绘制`x`次。 

如果我们表示为`f(k)`至少重新绘制的黑色单元格数量`k`次，那么我们需要的答案是：```
f(x) - f(x + 1)
```因为这些正是能够存活下来重新绘制的细胞`x - 1`但不超过。 

计算矩形内的黑色单元格很容易。 由于左上角是黑色的，因此一个单元格中黑色单元格的数量`a × b`矩形是：```
(a * b + 1) // 2
```当以相同的奇偶校验对齐方式计数时。 

这将整个问题简化为一些算术运算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nm · 分钟(n, m)) | O(纳米) | 太慢了 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`n`,`m`， 和`x`。 
2. 定义函数`count_black(a, b)`返回黑色单元格的数量`a × b`左上角为黑色的矩形。 

公式为：```
(a * b + 1) // 2
```因为黑色和白色的单元格交替出现，当面积为奇数时，黑色获得额外的单元格。 
3.让`k = x - 1`。 

完全重新绘制的单元格`x`时代必须生存`x - 1`步子缩小。 
4. 计算至少存活下来的矩形的尺寸`x`重画：```
a1 = n - 2k
b1 = m - 2k
```如果任一维度为非正值，则没有细胞能存活那么久。 
5. 计算至少存活下来的矩形的尺寸`x + 1`重画：```
a2 = n - 2(k + 1)
b2 = m - 2(k + 1)
```6. 计算：```
at_least_x = count_black(a1, b1)
at_least_x_plus_1 = count_black(a2, b2)
```将非正尺寸的矩形视为包含零个单元格。 
7.最终答案是：```
at_least_x - at_least_x_plus_1
```### 为什么它有效

 仅当所有四个对角邻居也都在上一步中幸存下来时，才可以再次重新绘制黑色单元。 该条件在每次迭代期间从每个边界中恰好删除一个对角层。 

后`k`迭代中，幸存的单元格正是去除后得到的矩形内的黑色单元格`k`来自所有四个侧面的行和列。 

所以`f(k)`至少正确计算重新绘制的单元格`k`次。 减去连续层可以精确地隔离重新绘制的单元格`x`次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_black(a, b):
    if a <= 0 or b <= 0:
        return 0
    return (a * b + 1) // 2

def solve():
    n, m = map(int, input().split())
    x = int(input())

    k = x - 1

    at_least_x = count_black(n - 2 * k, m - 2 * k)
    at_least_x_plus_1 = count_black(n - 2 * (k + 1), m - 2 * (k + 1))

    print(at_least_x - at_least_x_plus_1)

solve()
```辅助函数处理问题的几何核心。 如果剩余矩形的尺寸为非正数，则没有细胞能够存活那么多层，因此该函数立即返回零。 

表达式`(a * b + 1) // 2`计算棋盘图案中的黑色单元格，从左上角的黑色开始。 这适用于偶数和奇数区域。 

变量`k = x - 1`表示一个单元格必须存活多少次收缩操作才能被准确地重新绘制`x`次。 

该实现完全避免了模拟。 不需要数组、BFS 或递归。 一切都来自对角层的几何解释。 

一个容易犯的错误是混淆了“准确地绘制”`x`次”与“幸存`x`轮”。精确绘制的单元格`x`时代只有通过回合才能生存`x - 1`，这就是代码使用的原因`k = x - 1`。 

计算下一层时会出现另一个常见的差一问题。 我们减去`2 * (k + 1)`因为每次额外的重新绘制都会从每一侧删除一行和一列。

import io

def solve():

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    out = io.StringIO()
    backup = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup
    return out.getvalue().strip()

 ## 边缘情况

 考虑单排板：```
1 5
1
```该算法计算：```
k = 0
a1 = 1
b1 = 5
a2 = -1
b2 = 3
```所以：```
at_least_x = 3
at_least_x_plus_1 = 0
```答案是`3`。 

这是正确的，因为每个黑色单元格每分钟都会被绘制一次`0`，但没有单元格有四个对角邻居，因此重新绘制永远不会继续。 

现在考虑：```
3 3
2
```我们计算：```
k = 1
a1 = 1
b1 = 1
a2 = -1
b2 = -1
```所以：```
at_least_x = 1
at_least_x_plus_1 = 0
```答案是`1`。 

只有中心单元能够存活足够长的时间，可以重新粉刷两次。 第一层收缩后，角部黑色单元消失。 

最后，考虑一个均匀尺寸的板：```
2 3
1
```剩下的矩形为`x = 1`是完整的董事会本身：```
2 × 3
```黑色单元格的数量为：```
(2 * 3 + 1) // 2 = 3
```这证实了棋盘计数公式可以正确处理混合奇偶校验维度。
