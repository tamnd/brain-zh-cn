[CF 6C - 爱丽丝、鲍勃和巧克力](https://codeforces.com/problemset/problem/6/C)

 **评分：** 1200
 **标签：** 贪心、两个指针
 **求解时间：** 1m 29s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们有一排巧克力棒，每块巧克力棒都需要一定的时间来吃。 爱丽丝从左端开始，一直向右移动。 鲍勃从右端开始，一直向左移动。 两人都不间断地连续吃东西，没有人可以吃完一块巧克力而中途停下来。 

有趣的是，这个过程是由时间决定的，而不是轮流决定的。 如果爱丽丝比鲍勃先吃完当前的巧克力，她会立即开始吃她这边的下一块巧克力。 鲍勃的情况也是如此。 最终两个玩家在中间相遇。 如果他们在同一时刻开始吃同样的巧克力，爱丽丝就会得到那块巧克力，而鲍勃就会停下来。 

输入只是一个数组，其中每个元素代表吃一颗巧克力所需的时间。 输出询问最后爱丽丝吃了多少巧克力以及鲍勃吃了多少巧克力。 

限制足够大，我们必须仔细考虑效率。 巧克力数量可达$10^5$，所以任何二次解都会围绕$10^{10}$最坏情况下的操作，远远超出了 2 秒运行时间的限制。 线性时间是这里的自然目标。 由于我们只需要从两端按顺序处理巧克力，因此强烈建议采用双指针方法。 

有一些边缘情况可以悄悄地破坏不正确的实现。 

考虑一块巧克力：```
1
5
```正确的输出是：```
1 0
```Alice首先从左边开始，Bob从右边开始，但是两个位置是相同的。 爱丽丝收到巧克力是因为她有领带。 粗心的实施可能会错误地为每个玩家提供一块巧克力。 

另一个棘手的情况是，当两个玩家在到达中间之前累积相同的进食时间时：```
3
2 2 2
```正确的输出是：```
2 1
```Alice 在 2 秒内吃掉第一块巧克力，Bob 在 2 秒内吃掉最后一块巧克力，现在两人将同时开始吃中间的巧克力。 爱丽丝收到了。 

当一方进步更快时，就会出现不同的错误来源：```
5
1 100 1 1 1
```正确的输出是：```
1 4
```爱丽丝在大巧克力上停留了很长时间，而鲍勃很快就吃掉了右边的几块巧克力。 交替轮流而不是比较累积时间的实现在这里将会失败。 

## 方法

 直接模拟是第一个自然的想法。 我们可以想象跟踪 Alice 和 Bob 的确切当前时间，以先完成的玩家为准。 每个玩家一颗一颗地吃掉巧克力，我们不断地决定谁是下一个获得自由的人。 

这种强力模拟实际上是正确的，因为该过程本身是连续的和确定性的。 问题在于，幼稚的实现可能会重复搜索下一个事件或不必要地重新计算时序。 如果我们逐个时间单位模拟时间单位，则运行时间将变得灾难性的，因为巧克力时间的总和可能高达$10^8$。 

关键的观察是我们永远不需要模拟单个秒。 在任何时刻，唯一重要的信息是 Alice 已经花费的总时间和 Bob 已经花费的总时间。 

假设爱丽丝花费的总时间少于鲍勃。 这意味着爱丽丝更早完成并首先获得自由，因此她必须拿走左边的下一块巧克力。 同样，如果鲍勃花费的总时间较少，他必须拿走右边的下一块巧克力。 

这将整个过程变成了一个非常紧凑的贪心程序。 我们维护两个指针，一个来自左侧，一个来自右侧，以及两位玩家的累计进食时间。 在每一步中，总时间较短的玩家都会获得下一个可用的巧克力。 

问题的结构使得这种贪婪的选择是安全的，因为吃饭顺序是由完成时间决定的。 没有人可以跳过一块巧克力或故意等待，因此下一步行动取决于谁先有空。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O（总进餐时间）或更糟 | O(1) | O(1) | 太慢了 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.初始化两个指针：

 -`left = 0`为了爱丽丝这边。 
-`right = n - 1`为了鲍勃这边。 
2、维持累计进食次数：

 -`alice_time = 0`-`bob_time = 0`3. 维护已吃巧克力的计数器：

 -`alice_count = 0`-`bob_count = 0`4. 继续`left <= right`。 

每一步都要比较`alice_time`和`bob_time`。 
5. 如果`alice_time <= bob_time`，Alice 首先变得可用，或者两者同时变得可用。 

爱丽丝在索引处拿走了巧克力`left`。 

将进食时间添加到`alice_time`, 增量`alice_count`，并移动`left`右一步。 

平等的情况很重要，因为关系属于爱丽丝。 
6. 否则，Bob 首先有空。 

鲍勃在索引处拿走了巧克力`right`。 

将进食时间添加到`bob_time`, 增量`bob_count`，并移动`right`还剩一步。 
7. 当指针交叉时，每块巧克力都已分配完毕。 打印两个计数器。 

### 为什么它有效

 不变的是，在每一步之前，区间外的每块巧克力`[left, right]`已被永久分配给一位玩家，并且`alice_time`和`bob_time`代表每个玩家迄今为止花费的确切总时间。 

如果爱丽丝消耗的总时间少于鲍勃，她必须更早完成并立即开始她这边的下一个可用巧克力。 鲍勃无法先拿到那块巧克力，因为他还在忙着吃东西。 同样的推理同样适用于鲍勃。 

当两个总数相等时，两个玩家同时获得自由。 该声明明确表示爱丽丝在这种情况下收到了共享的巧克力，这正是该条件使用的原因`<=`。 

由于每个步骤都与真实过程完全匹配，因此算法会产生正确的最终计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
t = list(map(int, input().split()))

left = 0
right = n - 1

alice_time = 0
bob_time = 0

alice_count = 0
bob_count = 0

while left <= right:
    if alice_time <= bob_time:
        alice_time += t[left]
        alice_count += 1
        left += 1
    else:
        bob_time += t[right]
        bob_count += 1
        right -= 1

print(alice_count, bob_count)
```解决方案直接遵循贪心模拟。 

两个指针代表剩余无人认领的巧克力。 该间隔之外的所有东西都已经被吃掉了。 

之间的比较`alice_time`和`bob_time`是核心思想。 如果爱丽丝花费的总时间少于或等于总时间，她一定是下一个获得自由的玩家，因此她从左侧拿走下一块巧克力。 

平等的情况很微妙。 使用`<`而不是`<=`会错误地同时给鲍勃巧克力，这违反了声明。 

循环条件也很重要。 我们继续，同时`left <= right`，不仅仅是`<`。 当只剩下一块巧克力时，仍然必须正确分配它，通常是由于平局规则而分配给爱丽丝。 

所有变量都适合 Python 整数，因为总进食时间最多为$10^8$。

 ## 边缘情况

 考虑尽可能最小的输入：```
1
5
```最初两个累积时间均为零，因此条件`alice_time <= bob_time`是真的。 爱丽丝拿走了唯一的一块巧克力，她的计数变成了 1，指针立即交叉。 

最终输出是：```
1 0
```此案例证实该算法正确处理剩余的一块巧克力并遵守平局规则。 

现在考虑中间关系场景：```
3
2 2 2
```前两个动作之后：

 - 爱丽丝已经花了 2 秒。 
- 鲍勃已经花了 2 秒。 
- 只剩下中间的巧克力。 

因为该算法使用`<=`，爱丽丝收到了最后一块巧克力。 输出变为：```
2 1
```如果条件写成`<`，鲍勃会错误地收到中间的巧克力。 

最后，考虑一个玩家快速消耗大量巧克力的情况：```
5
1 100 1 1 1
```一步一步：

 - 爱丽丝吃东西`1`，总计变为 1。 
- 鲍勃吃东西`1`，总计变为 1。 
- Alice 和 Bob 打成平手，所以 Alice 开始`100`。 
- 然后鲍勃在爱丽丝仍然忙碌的时候吃掉了剩下的三块巧克力。 

输出是：```
1 4
```这验证了该算法正确地模拟了实际经过的时间，而不是机械地交替转动。
