 ## 解决方案
 ## 问题理解

 艾伦遵循固定的时间表去健身房$N$天。 当天$i$，他必须准确举起$X[i]$克，他从基础力量开始$K$。 他可以在去健身房的任何一天购买锻炼前饮料来永久增强体力。 每喝一杯都会使他的力量增加固定量$A$，费用取决于当天的健身房，由下式给出$C[i]$。 他可能会购买多种饮料，但每次购买都与一天的健身房相关，并贡献相同的力量增长。 

这种限制是暂时的：如果他在某些日子购买了饮料，那么从那天起他只能依靠增加的力量。 任务是选择购买饮料的日期，以便每天$i$，他累积的力量至少为$X[i]$，同时最小化总成本。 如果即使喝所有饮料也不可能，答案是-1。 

约束条件达到$N = 10^5$，这立即排除了对购买决策子集的任何二次枚举。 任何有效的解决方案都必须以线性或接近线性的时间处理这些天，通常使用带有堆或基于排序的结构的贪婪选择。 

当早期需要高浓度但昂贵的饮料出现较早而廉价的饮料出现较晚时，就会出现微妙的失败案例。 当当前实力不足时贪婪地买入的幼稚策略可能会失败，因为它可能会锁定昂贵的早期买入，而不是等待更便宜的未来机会。 

当每天买一杯饮料都不够时，就会出现另一种边缘情况。 例如，如果$K + N \cdot A < \max X[i]$，那么任何策略都无法满足要求，但粗心的实现仍然可能会尝试模拟和溢出或行为不正确。 

## 方法

 直接的暴力方法会每天考虑是否买饮料。 由于每次购买都会永久增加强度，因此这成为一个子集选择问题$N$天，给予$2^N$的可能性。 即使通过可行性进行修剪，仍然会留下指数分支，因为每个决策都会影响所有未来的约束。 

关键的观察是，买一杯饮料只有当它可以防止有一天失败时才有意义。 如果当天$i$，当前强度不足以$X[i]$，那么我们一定在之前或当时购买了足够的饮料$i$。 这个问题变成了一个调度问题：确保我们每天都积累了足够的“力量预算”，同时选择尽可能最便宜的饮酒时间。 

重新构建问题的一个有用方法是按顺序处理日期，同时保持到目前为止需要多少饮料。 如果在白天$i$，目前的强度太低，我们被迫添加更多的饮料。 问题是从哪里获取这些饮料。 由于每种饮料的功效相同，但成本不同，我们总是想在已经过去的日子里选择最便宜的。 这自然会导致维护候选成本的数据结构并在需要时选择成本最低的饮料。 

这将问题转化为一个贪婪的累积过程，其中最小堆超过了先前几天的成本。

 | ---| ---| ---| ---|
 | 蛮力 | O(2^N) | O(2^N) | O(N) | 太慢了 |

 ## 算法演练

 我们从左到右扫描几天，记录我们已经购买了多少饮料以及可供选择的可用健身费用。 

1. 初始化电流强度为$K$，总成本为 0，最小堆将存储迄今为止处理的所有天的成本。 
2. 每天$i$， 插入$C[i]$放入堆中，因为现在可以选择在这一天或之前购买饮料。 
3. 检查电流强度是否$K + (\text{drinks bought so far}) \cdot A$遇见$X[i]$。 如果是，请继续而不购买任何东西。 
4、如果不满足$X[i]$，计算需要多少额外饮料才能达到$X[i]$。 每杯饮料都添加$A$，因此我们确定所需的最少饮料数量。 
5. 反复从堆中提取最小成本并模拟购买饮料，直到满足所需的饮料数量。 每次提取都对应于在这一天或之前选择最便宜的可用健身房。 
6. 如果在满足要求之前堆变空，则输出 -1，因为没有未来的选项可以修复之前的故障。 
7. 继续此过程一整天，累计总成本。 

关键机制是我们从不提前承诺购买饮料。 相反，我们保留所有过去的选项，并且仅在违反约束时才激活最便宜的选项。 

### 为什么它有效

 任何一天$i$，如果我们需要额外的强度，任何有效的解决方案都必须至少包括几天内购买的一定数量的饮料$1$到$i$。 在所有这些有效的解决方案中，用具有相同前缀的更便宜的可用饮料替换任何选定的饮料只能提高或保持可行性。 这种交换论证确保了每当我们被迫购买时贪婪地选择最便宜的可用成本是最优的，并且推迟决策永远不会从考虑中排除更好的选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, k = map(int, input().split())
    x = list(map(int, input().split()))
    a = int(input())
    c = list(map(int, input().split()))

    heap = []
    total_cost = 0
    drinks = 0  # number of drinks bought so far

    for i in range(n):
        heapq.heappush(heap, c[i])

        current_strength = k + drinks * a

        if current_strength >= x[i]:
            continue

        # need more drinks
        needed = (x[i] - current_strength + a - 1) // a

        while needed > 0:
            if not heap:
                print(-1)
                return
            total_cost += heapq.heappop(heap)
            drinks += 1
            needed -= 1

    print(total_cost)

if __name__ == "__main__":
    solve()
```该堆存储从几天到当前索引的所有可能的饮料成本。 这确保了当我们被迫增加力量时，我们总是选择迄今为止最便宜的有效健身房。 

这`drinks`计数器追踪我们已经承诺的永久提升数量。 从所需的强度差距到饮料数量的转换使用上限除法，因为每种饮料的贡献完全相同$A$。 

正确性取决于永远不要将成本排除在外，并且在被迫时始终选择最低成本。

    import heapq

    a = int(input())

 ## 边缘情况

 当在几次便宜的机会之后强度需求急剧上升时，就会出现关键的边缘情况。 该算法确保了正确性，因为所有过去的健身房成本都保留在堆中，因此即使较晚的一天需要多次提升，它仍然可以选择较早的便宜选项，而不是被迫进入昂贵的较晚选项。 

另一个边缘情况是没有一天需要喝酒，这意味着所有$X[i] \le K$。 堆仍然填满，但不会发生弹出操作，并且答案仍然为零。 这证实了永远不会触发不必要的购买。 

最后一个边缘情况是当所需的饮料数量超过$N$。 在这种情况下，堆在我们满足需求之前就被清空了，并且算法正确地输出-1，这反映出即使最大的提升也无法达到所需的强度配置文件。
