 ## 解决方案
 ## 问题理解

 我们给定一个固定的整数`n`和一个整数范围`0, 1, 2, ..., m`。 该范围内的每个数字都与`n`，产生一组值。 从这个结果集中，我们想要未出现的最小非负整数。 

思考这个问题的一个有用方法是我们采用索引区间`[0, m]`，应用按位变换`i → n ⊕ i`，然后询问转换后的集合中缺少的第一个整数。 

重要的结构事实是，具有固定数字的 XOR 是所有整数上的双射，因此不会产生全局冲突。 某些数字缺失的唯一原因是原始域被截断为`[0, m]`。 

约束条件很大，测试用例多达 30,000 个，值高达`10^9`。 这排除了整个范围内的任何模拟或每个值的检查。 任何解决方案都必须在每个测试用例的恒定或对数时间内运行，本质上是在二进制表示级别上工作。 

一个天真的尝试是生成所有值`n ⊕ i`为了`i`在`[0, m]`，对它们进行排序，并计算 mex。 这已经失败了，因为`m`可以很大，使范围达到`10^9`在最坏的情况下，这远远超出了可行的范围。 

一个更微妙的失败案例来自于尝试构建一个集合并逐步检查成员资格`0, 1, 2, ...`。 尽管每次成员资格检查都是 O(1)，但 mex 本身可以大到`10^9`，因此循环仍可能退化为答案大小的线性时间。 

关键的观察是我们不需要整套。 我们只需要了解谓词如何`x is present ⇔ (n ⊕ x) ≤ m`表现在位结构上。 

## 方法

 暴力方法枚举了每一个`i`在`[0, m]`，计算`n ⊕ i`，将结果存储在集合中，然后递增`mex`直到找到缺失值。 这是正确的，因为它直接构造了整个变换集。 然而，其成本与`m`，最多可达`10^9`，所以无法使用。 

结构的简化来自于成员资格的重写。 一个数字`x`当且仅当存在一些`i ∈ [0, m]`这样`x = n ⊕ i`。 XOR 是可逆的，所以这相当于说`i = n ⊕ x`在于`[0, m]`。 因此，隶属度成为一个单一的不平等条件：`x is present ⇔ (n ⊕ x) ≤ m`。 

这就把问题变成了寻找最小的`x`这样`(n ⊕ x) > m`。 

现在的任务是一个经典的按位构造问题：我们正在构造最小的整数`x`这样导出的值`n ⊕ x`超过一个界限。 困难在于异或破坏了单调性，因此我们不能简单地进行数值比较； 我们必须构建`x`一点一滴地追踪我们是否还能保持`(n ⊕ x)`在界限之内。 

我们使用从最高有效位到最低有效位的贪婪数字DP来解决这个问题。 对于每一位，我们决定是否将该位设置为`x`仍然可以允许完成剩余位，以便`(n ⊕ x) ≤ m`。 如果可能的话，我们会保持小一点； 否则，我们将被迫设置它。

 | --- | --- | --- | --- |
 | 蛮力 | 每次测试 O(m) | O(米) | 太慢了|

 ## 算法演练

 我们从可能出现的最高位开始一点一点地构建答案`n`或者`m`。 

1. 初始化`x = 0`。 我们将从最高有效位向下构建答案。 施工确保`x`是满足的最小数`(n ⊕ x) > m`。 
2. 对于每个位位置`b`从高到低，我们尝试设置这一点`x`到`0`第一的。 这相当于按照字典顺序（二进制）使答案尽可能小。 
3. 暂时固定前缀后`x`，我们询问是否仍然可以选择剩余的较低位，以便`(n ⊕ x) ≤ m`成立。 这是一个关于后缀位的可行性问题。 
4. 为了检查可行性，我们模拟了满足不等式的最佳情况。 对于固定前缀，低位`x`可以自由选择，这意味着低位`(n ⊕ x)`也可以自由变化。 因此，唯一重要的约束是已经固定的较高位是否强制`(n ⊕ x)`超过`m`或者仍然让它保持在下方。 
5. 如果可行性成立，我们将当前位保留为`0`并继续。 如果可行性失败，则意味着选择`0`会使它无法保留`(n ⊕ x) ≤ m`，所以我们必须将该位设置为`1`。 
6. 继续，直到处理完所有位。 由此产生的`x`是满足以下条件的最小整数`(n ⊕ x) > m`。 

### 为什么它有效

 该算法是对二进制前缀的贪婪构造，其中约束是之间的前缀比较`(n ⊕ x)`和`m`。 在每一步中，我们都保留当前前缀存在某种补全的不变量`(n ⊕ x)`在允许的范围内，除非我们故意强迫它超出范围。 因为我们总是选择最小的可行位`x`，我们第一次被迫打破可行性正是在这个点上`(n ⊕ x)`必须超过`m`。 这保证了构建的`x`在所有有效候选人中是最小的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n, m):
    x = 0

    for b in range(30, -1, -1):
        candidate = x | (1 << b)

        # check if this prefix of x can still allow (n xor x) <= m
        # we simulate feasibility by greedily completing lower bits optimally
        ok = True
        cur_x = candidate
        cur_val = 0

        # we test bit by bit whether (n xor cur_x) can stay <= m
        # using a tight-style simulation
        tight = True

        for i in range(30, -1, -1):
            nb = (n >> i) & 1
            xb = (cur_x >> i) & 1
            vb = nb ^ xb

            mb = (m >> i) & 1

            if tight:
                if vb < mb:
                    tight = False
                elif vb > mb:
                    ok = False
                    break

        if not ok:
            x |= (1 << b)

    return x

def main():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        print(solve_case(n, m))

if __name__ == "__main__":
    main()
```代码从最高位开始贪婪地构建答案。 对于每个候选位，它检查选择该位是否仍然允许`(n ⊕ x)`最多保留`m`。 可行性检查是通过比较前缀来实现的`(n ⊕ x)`和`m`在数字 DP 式扫描中。 

一个微妙的点是我们没有显式枚举低位的所有完成。 相反，我们依赖这样一个事实：一旦前缀`(n ⊕ x)`变得严格小于相应的前缀`m`，所有剩余的完成都是安全的。 如果它变得更大，则该选择无效。

 ## 边缘情况

 当`m = 0`，序列仅包含`n ⊕ 0 = n`，所以墨西哥是`0`除非`n = 0`，在这种情况下，墨西哥变成`1`。 该算法可以正确处理此问题，因为检查的第一个值始终是`x = 0`，并且可行性失败恰好在`n`已经是`0`。 

什么时候`n = 0`，序列很简单`[0, 1, ..., m]`，所以墨西哥是`m + 1`。 按位构造重现了这一点，因为`(0 ⊕ x) = x`，所以条件简化为找到第一个大于的整数`m`。 

什么时候`n`和`m`较大且共享高位，早期决策在高位确定，而较低位变得无关紧要。 贪心构造正确地解决了最高不同位的答案，因为这就是可行的地方`(n ⊕ x) ≤ m`首先被打破。
