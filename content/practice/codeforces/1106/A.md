 ## 解决方案
 ## 问题理解

 我们有一个方形网格，其中填充了两个可能的字符，`X`和`.`。 任务是扫描该网格的每个内部单元，并确定它是否是由对角线形成的“十字”图案的中心。 

一个位置`(i, j)`仅当单元本身及其四个对角邻居都为十字中心时，才符合十字中心的条件`X`。 具体来说，所需的五个单元格是`(i, j)`,`(i-1, j-1)`,`(i-1, j+1)`,`(i+1, j-1)`， 和`(i+1, j+1)`。 

输出只是网格中此类有效中心的数量。 

网格大小最多为`500 × 500`，这意味着最多 250,000 个单元。 用恒定的工作量检查每个单元格是完全可行的，但是任何重复扫描更大模式或重新检查昂贵条件的解决方案仍然会通过，除非它意外地在更深的循环中引入了不必要的重复工作。 

一个微妙的边缘情况是网格太小而无法包含任何有效中心。 如果`n < 3`，不存在具有所有四个对角邻居的单元格，因此答案始终为零。 另一个边缘情况出现时`X`簇存在，但对角线不完整，例如完整的加号行或列`X`没有帮助，因为只有对角线很重要。 

一个典型的错误是仅检查四个方向的邻接性或错误地使用正交邻居而不是对角线。 另一个错误来自于忘记边界检查，尤其是在`i = 1`,`i = n`,`j = 1`,`j = n`，其中对角线访问会出界。 

## 方法

 暴力解决方案很简单。 对于每个细胞`(i, j)`在网格中，我们尝试通过检查四个对角邻居加上其自身来验证它是否是有效中心。 每次检查都需要恒定的时间，因此总复杂度为`O(n^2)`。 由于每次验证仅检查五个单元，因此这种方法在渐近行为方面已经是最佳的。 

这种方法之所以有效，是因为交叉的条件完全是局部的。 不同候选中心之间不存在依赖性，因此不需要预处理或动态规划。 每个单元都可以独立评估。 

任何进一步优化的尝试都不会改变复杂性类别，因为我们已经接触了每个单元格一次。 唯一的“优化”是仔细的边界处理并避免内部检查内的冗余计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 | O(n²) | O(1) 额外 | 已接受 |
 | 最佳| O(n²) | O(1) 额外 | 已接受 |

 ## 算法演练

 1. 将网格大小和网格本身读入内存。 我们将其存储为字符串列表，因此索引的复杂度为 O(1)。 这允许直接字符访问而无需解析开销。 

2. 将计数器初始化为零。 这将累积有效交叉中心的数量。 

3. 迭代所有单元格`(i, j)`这样`1 < i < n - 1`和`1 < j < n - 1`。 我们跳过边界，因为有效的中心需要四个对角邻居。 

4. 对于每个候选单元格，检查所有五个必需位置是否包含`X`。 如果其中任何一个不是`X`，细胞立即被拒绝。 一旦发现不匹配，这种早期拒绝可以避免不必要的检查。 

5. 如果满足所有条件，则递增计数器。 

6. 扫描整个网格后，输出计数器。 

### 为什么它有效

 每个有效的交叉都由其中心单元格唯一标识。 十字的定义仅取决于一组固定的五个位置，因此检查这五个单元格既是必要的也是充分的。 如果不使这些精确的对角线位置等于`X`。 由于每个候选中心都只测试一次并且不会跳过任何有效配置，因此该算法对所有交叉只计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    grid = [input().strip() for _ in range(n)]

    if n < 3:
        print(0)
        return

    ans = 0

    for i in range(1, n - 1):
        for j in range(1, n - 1):
            if (grid[i][j] == 'X' and
                grid[i - 1][j - 1] == 'X' and
                grid[i - 1][j + 1] == 'X' and
                grid[i + 1][j - 1] == 'X' and
                grid[i + 1][j + 1] == 'X'):
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```实现直接遵循算法：我们仅迭代有效的内部单元并显式测试五个​​所需的位置。 早期的`n < 3`check 可以防止不必要的循环，也使边界逻辑更清晰。 

实施中的一个常见错误是混淆`(i-1, j+1)`和`(i+1, j-1)`或者完全忘记一条对角线。 另一个微妙的问题是意外地迭代`0`到`n-1`然后在循环内添加边界检查，这会增加混乱和差一错误的风险。

 ## 边缘情况

 对于`n = 1`或者`n = 2`，该算法在任何循环执行之前立即返回零。 这与没有单元格具有四个对角邻居的事实相符。 

对于完全填充的网格`X`，每个内部单元都会被检查，但大多数都会失败，因为相邻中心的对角线重叠不正确。 例如，在一个`3×3`全部的网格`X`，中心是有效的，但在较大的网格中，边界相邻的候选者由于缺少对角线而失败。 

对于稀疏网格，其中`X`形成垂直或水平线，由于不存在对角线结构，因此未检测到交叉。 该算法正确地检查了所有候选者，但由于缺少对角线匹配而拒绝它们。 

每个案例都证实该决定纯粹是本地的，并且完全由每个候选人的五单元检查捕获。
