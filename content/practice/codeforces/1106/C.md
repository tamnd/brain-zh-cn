 ## 解决方案
 ## 问题理解

 我们给出了一个偶数长度的正整数列表，我们必须将这些数字分组。 每个组必须至少包含两个元素，并且每个数字必须恰好属于一个组。 对于每个组，我们计算其元素的总和，对该总和进行平方，然后对所有组中的这些平方值求和。 目标是选择使总数最小化的分组。 

看待该任务的另一种方式是，我们正在决定如何对数字进行“聚类”，以使随着每个聚类总和呈二次方增长的惩罚尽可能小。 大的总和是昂贵的，因为平方会放大它们，因此在组之间分配数字是有益的，但组仍然必须包含至少两个元素，这可以防止微不足道的单元素分裂。 

限制很大，最多有 300,000 个数字。 这立即排除了任何尝试枚举分区甚至与子集上的动态编程配对的方法。 任何解决方案都必须接近线性或 n log n，因为 n log n 排序已经接近实际极限，并且任何二次方都是不可能的。 

“每组至少 2 个元素”的要求产生了一个微妙的问题。 任意配对元素或贪婪地合并局部小值的幼稚贪婪策略可能会失败，因为组大小与平方和之间的相互作用是非线性的。 例如，以任意顺序配对相邻元素可能远非最佳。 

另一个失败案例来自于认为“始终将最小的元素组合在一起”是最佳的。 考虑一个像这样的数组`[1, 1, 100, 100]`。 将小数字配对在一起和将大数字配对在一起产生`(1+1)^2 + (100+100)^2 = 4 + 40000 = 40004`。 交叉配对给出`(1+100)^2 + (1+100)^2 = 10201 + 10201 = 20402`，它要小得多。 这表明平衡总和比本地分组更重要。 

## 方法

 强力解释是考虑将数组划分为大小至少为 2 的有效组的所有可能方法。 即使限制配对，匹配的数量也已经是指数级的，并且允许任意大小的组使得搜索空间相当于集合分区，其以超指数方式增长（贝尔数）。 对于n = 30，这已经是不可行的； 对于 n = 300,000 来说这是完全不可能的。 

关键的观察来自于重写目标。 扩大一个正方形给出：$$(\sum a_i)^2 = \sum a_i^2 + 2\sum_{i<j} a_i a_j$$无论分组如何，各个平方的总和都是固定的。 改变的是交叉项，这取决于将哪些元素放置在一起。 因此，最小化目标相当于最小化组内成对乘积的总和。 

这改变了观点：我们想要决定哪些元素进行乘法交互。 为了降低成本，我们希望大型元素避免与其他大型元素组合在一起。 将较大的值分散到不同的组中可以减少较大的叉积。 同时，由于每个组必须至少有两个元素，因此我们不能完全隔离元素。 

最优结构是通过排序产生的。 如果我们对数组进行排序，最好的策略是将最小的与最大的配对，第二小的与第二大的配对，依此类推。 这样可以平衡每个组内的总和并最大限度地减少极端的二次增长。 这种配对结构是最佳的，因为将两个大元素带入同一组的任何偏差都会比其他地方任何可能的补偿更多地增加二次项。 

我们正好形成 n/2 个大小为 2 的组。较大的组始终可以分成对，而不会增加最佳配置中的成本，因为拆分会减少总和的方差并减少平方惩罚。

 ## 算法演练

 1. 对数组进行非降序排序。 此步骤对于构建元素是必要的，以便我们可以系统地平衡大值和小值。 
2. 将最小的元素与最大的元素配对，将第二小的元素与第二大的元素配对，并继续向内，直到所有元素都配对。 这确保每个组都有两个元素，并且通过将它们与大小相反的元素配对来中和极端值。 
3. 对于每一对，计算总和并平方，然后累加得到答案。 此时分组是固定的，因此我们只评估成本。 
4. 输出组平方和的总和。 

关键的决定是在排序后强制对称配对。 如果没有排序，配对是任意的，并且可能产生高度不平衡的总和，从而导致较大的二次惩罚。 

### 为什么它有效

 平方目标会惩罚不平衡。 当两个大值放在一起时，它们的乘积项会变得非常大。 通过配对极端，我们将质量均匀地分配给各组。 任何将两个大元素放在同一组中的尝试都可以转换为将它们分开的配置，并且由于平方函数的凸性，这种转换严格降低了目标。 这个交换参数确保排序的相反配对是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

a.sort()

ans = 0
for i in range(n // 2):
    s = a[i] + a[n - 1 - i]
    ans += s * s

print(ans)
```该解决方案首先对数组进行排序，以便配对决策变得结构化。 该循环恰好运行 n/2 次，每次都从排序列表中的对称位置形成一组。 直接计算每对的总和、平方并累加。 

一个微妙的一点是，我们永远不会组建超过二号的团体。 尽管该问题允许更大的组，但任何最佳配置都可以转换为基于配对的配置，而不会增加成本，因此限制对是安全的。 

整数溢出在 Python 中不是问题，但在其他语言中，必须确保 64 位整数，因为每组值可以达到大约 (2 * 10^4)^2 并累积超过 1.5e5 组。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    ans = 0
    for i in range(n // 2):
        ans += (a[i] + a[n - 1 - i]) ** 2

    return str(ans)

 ## 边缘情况

 对于最小的输入`n = 2`，算法形成一个组并输出`(a1 + a2)^2`。 排序不会改变结果，因此正确性是立即的。 

对于像这样的均匀数组`[x, x, x, x]`，以任何方式配对都会产生相同的总和，但排序配对可以保留正确性并避免对替代分组进行不必要的推理。 

对于交替的极值，例如`[1, 100, 1, 100, 1, 100]`，排序创建`[1, 1, 1, 100, 100, 100]`，并且配对极值确保每个大值与小值匹配，从而防止二次爆炸将大值分组在一起。
