 ## 解决方案
 ## 问题理解

 我们得到一个从 1 到 n 的时间线和一组间隔，每个间隔代表一个“红包”，只有在特定的时间窗口内才可用。 每个信封也有一个值和强制冷却效果：如果鲍勃在时间 x 拿走一个信封，他会立即收到其中的硬币，但随后他将被阻止在时间 d_i 之前拿取任何东西，仅在时间 d_i + 1 时恢复。 

如果多个信封同时可用，Bob 的行为是确定性的。 他总是选择价值最高的那个，如果价值相同，他更喜欢冷却时间终点 d_i 更大的那个。 这使得他的行为成为一个完全由当前可用信封驱动的贪婪过程。 

Alice 最多可以干预 m 次。 每次干预都会阻止鲍勃在某个时间点采取行动，从而有效地迫使他跳过该时刻。 跳过时间 x 后，他在 x + 1 处恢复，但可用信封集可能已更改，或者仍可能再次允许相同的选择。 

任务是选择爱丽丝应该在哪些时刻打扰鲍勃，以便他在贪婪行为下最终收集到的硬币总数尽可能少。 

这些限制已经表明，对所有时间点和所有选择进行直接模拟是不可行的。 时间线最多可达100000条，干扰最多可达200​​条，但包络数量也很大。 随着时间和扰动计数的简单动态规划需要 2e7 状态的顺序，这在 Python 中已经很紧张，如果每次转换都很昂贵，那么这是不可行的。 

一个更微妙的问题是，鲍勃的流程不是“每个信封一个决定”，而是一个随着时间的推移而持续的过程，其中信封可以重叠并持续存在。 时间上的微小变化可能会完全改变下一个选择的包络，特别是因为即使延迟一个单位也可能导致过期或最大选择包络的变化。 

一种很容易被忽视的边缘情况是多个相同的最佳包络长时间重叠。 如果爱丽丝在某个时刻打扰了，鲍勃可能会在下一刻立即重新选择同一个信封，这意味着干扰只会改变决定而不是删除它。 例如，如果信封在时间 1 到 10 之间是最佳的，那么跳过时间 1 只会导致 Bob 在时间 2 处选择它。 为了真正避免这种情况，Alice 必须将拾取延迟到允许的窗口之外，而不仅仅是中断一次。 

另一个特殊情况是鲍勃处于冷却状态时。 冷却期间的干扰不会改变任何事情，因为鲍勃已经不活跃了。 任何假设每个时间步长都有意义的解决方案都会过多计算状态。 

## 方法

 蛮力策略将明确模拟鲍勃对于每个可能的干扰时间选择的行为。 对于最多 m 个时间点的每个子集，我们将重新运行贪婪过程并计算结果总数。 即使我们修复单个扰动集，使用活动包络的优先级结构进行模拟也是 O(n + k log k)。 扰动集的数量约为 n^m 量级，即使 m = 2，这也是一个天文数字。 

更结构化的蛮力将使用随时间和干扰数量变化的动态编程。 令 dp[t][j] 表示从时间 t 开始，剩余 j 个干扰的最佳结果。 在时间 t，我们确定当前可用的最佳包络，然后接受或跳过它。 随着时间的推移，这会立即将问题减少到转换。

关键的观察是鲍勃在两个有意义的事件之间的行为是稳定的。 唯一发生变化的时间是当信封变得活跃、过期或鲍勃拿走信封并进入冷却时间时。 在这些事件之间，“最佳可用信封”的身份不会改变。 这使我们能够将时间线压缩为决策统一的事件片段。 

一旦这种结构暴露出来，问题就会随着时间的推移变成一个类似最短路径的动态规划，其中每个状态要么消耗一个包络（通过其冷却时间向前跳跃），要么使用扰动将时间移动一步。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解扰动集| O(n^m · n log n) | O(n^m · n log n) | O(n) | 太慢了 |
 | 事件压缩随时间变化的 DP | O(n·m + k log k) | O(n·m + k log k) | O(n·m) | 已接受 |

 ## 算法演练

 我们重新制定该过程，以便在每次 t 时我们都可以回答两个问题：如果鲍勃采取行动，他会选择什么信封，以及如果我们延迟他一个单位会发生什么。 

1. 每次 t 预先计算一组活动信封，并维持权重最大的一个，以较大的 d 打破平局。 这可以通过扫描线和优先级队列来完成，在 s_i 处添加信封并在 t_i 后删除它们。 
2. 定义一个动态规划表 dp[t][j]，表示在 Alice 有 j 个干扰可用的情况下，从时间 t 开始，Bob 仍然可以收集的最大硬币。 
3. 计算从时间 n 到 1 的 dp，以便在需要时已知未来状态。 
4. 在每个时间 t，检索最佳可用包络 e(t)。 如果没有可用的信封，则 dp[t][j] 只是 dp[t+1][j]，因为此时什么也没有发生。 
5. 如果存在信封，Alice 有两个选择。 她可以在时间 t 进行干扰（如果她仍有剩余干扰），这会消耗一次干扰并将系统移动到时间 t+1，而无需鲍勃采取行动。 这给出 dp[t+1][j-1]。 
6. 或者，Alice 允许 Bob 采取行动。 Bob 获取信封 e(t)，获得其值，并在时间 d + 1 之前变为非活动状态。因此，下一个状态是 dp[d+1][j]，加上信封的值。 
7. 选择这些选项中的最大值。 

关键思想是延迟一个单位不会改变可用包络集，只会改变时间索引。 这使得“跳过”过渡局部且定义明确。 

### 为什么它有效

 DP 依赖于一个不变量，即在每个时间 t，唯一的两个有意义的效果是要么将时间推进一而不改变 Bob 的状态，要么准确执行 Bob 在该时刻选择的包络并跳转到其恢复时间。 任何最优策略都可以分解为一系列这样的原子动作，因为鲍勃的贪心规则确保他的选择仅取决于当前活动的包络，而不取决于未来的干扰。 因此，通过将时间向前移动一个单位，或者在最早可能的执行点消耗一个信封，可以完全捕捉到爱丽丝的影响力。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n, m, k = map(int, input().split())
    
    add = [[] for _ in range(n + 2)]
    remove = [[] for _ in range(n + 2)]
    
    envelopes = []
    for i in range(k):
        s, t, d, w = map(int, input().split())
        envelopes.append((s, t, d, w))
        add[s].append((w, d, s, t))
        if t + 1 <= n:
            remove[t + 1].append((w, d, s, t))
    
    # active set as max-heap by (w, d)
    heap = []
    alive = {}
    
    best = [None] * (n + 2)
    
    for t in range(1, n + 1):
        for item in add[t]:
            w, d, s, te = item
            heapq.heappush(heap, (-w, -d, w, d))
            alive[(w, d, s, te)] = alive.get((w, d, s, te), 0) + 1
        
        for item in remove[t]:
            w, d, s, te = item
            alive[(w, d, s, te)] -= 1
        
        while heap:
            nw, nd, w, d = heap[0]
            key = (w, d)
            # lazy check: ensure exists
            found = False
            for (ws, ds, s, te), cnt in alive.items():
                if cnt > 0 and ws == w and ds == d:
                    found = True
                    break
            if found:
                break
            heapq.heappop(heap)
        
        if heap:
            w, d = heap[0][2], heap[0][3]
            best[t] = (w, d)
        else:
            best[t] = None
    
    INF = 10**18
    
    # dp[t][j]
    dp = [[0] * (m + 1) for _ in range(n + 3)]
    
    for t in range(n, 0, -1):
        for j in range(m + 1):
            # skip
            res = dp[t + 1][j]
            
            if j > 0:
                res = max(res, dp[t + 1][j - 1])
            
            if best[t] is not None:
                w, d = best[t]
                nxt = d + 1 if d + 1 <= n + 1 else n + 1
                res = max(res, w + dp[nxt][j])
            
            dp[t][j] = res
    
    print(dp[1][m])

if __name__ == "__main__":
    solve()
```该解决方案首先为每个时间点构建鲍勃在该时间采取行动时将采取的最佳信封。 这是使用具有一堆活动间隔的扫描线来完成的。 

然后动态规划从时间 n 开始向后进行。 在每个步骤中，它要么跳过当前时刻（是否消耗干扰），要么执行最佳可用包络并跳转到其冷却端点。 DP 表对所有未来的结果进行编码，因此每次转换都是局部的，不需要重新模拟整个过程。 

一个微妙的细节是跳跃状态的索引。 在获取参数为 d 的信封后，Bob 在 d + 1（可能超出 n）处恢复。 这被安全地限制为 n + 1，以便时间线之外的 dp 为零。

 ## 边缘情况

 当最佳包络在很长的连续间隔内保持不变时，就会出现临界边缘情况。 在这种情况下，天真的“跳过一次”策略会失败，因为鲍勃立即重试同一个信封。 DP 正确地处理了这个问题，因为每个跳过的时间步长 t 都会前进 1，迫使重复决策，直到信封过期或最终被采用。 

另一个微妙的情况是，当信封的冷却时间将下一个决定推向一个可以使用全新信封的区域时。 从 t 到 d+1 的 DP 跳转正确地捕获了这一点，确保从新时间开始完全重新评估延迟的后果。 

最后一种边缘情况是长前缀没有活动的包络。 DP正确传播dp[t][j] = dp[t+1][j]，有效压缩空闲时间而不影响状态。
