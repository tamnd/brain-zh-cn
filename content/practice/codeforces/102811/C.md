 ## 解决方案
 ## 问题理解

 棋盘的每一行和每一列都恰好包含一个车，因此所有车的位置可以表示为排列。 输入数组`a`使用行号作为索引：`a[i]`告诉我们哪一列包含行中的车`i`。 

任务是将整个棋盘顺时针旋转 90 度并打印新的排列表示。 旋转后，每个车的行从其旧的列号发生变化，而其新的列取决于旧的行号。 

对于坐标处的车`(i, a[i])`，顺时针旋转将其坐标更改为`(a[i], N + 1 - i)`。 第一个坐标成为新行，第二个坐标成为新列。 答案数组必须存储每个新行的新列。 

板材尺寸可达`N = 100000`，因此任何明确模拟电路板的解决方案都是浪费的。 这种大小的棋盘将包含多达 100 亿个单元，这些单元无法放入内存中，也无法在典型的比赛时间限制内进行处理。 即使检查许多可能的行列对的方法也太慢，因此解决方案必须直接处理线性时间内的排列。 

几个小案例可能会破坏不正确的实现。 最常见的错误是忘记新行是旧列，而不是旧行。 例如，如果棋盘上有一辆车：```
1
1
```旋转后它仍然在唯一的单元格中：```
1
```在这种情况下，不考虑板尺寸而意外交换坐标的解决方案可能看起来是正确的。 

另一个常见的错误是使用`N - i`而不是`N + 1 - i`具有基于一的坐标。 例如：```
3
1
2
3
```车位于主对角线上。 旋转后它们应该变成：```
3
2
1
```因为第 1 行的车移动到第 3 列，所以第 3 行的车移动到第 1 列，依此类推。 直接对从一开始的输入使用从零开始的公式会产生不正确的值。 

第三个问题是在尝试就地转换数组时覆盖信息。 例如：```
4
2
4
1
3
```新位置由所有原始对确定`(row, column)`。 如果程序发生变化`a[2]`在使用第 2 行的原始值之前，结果取决于处理顺序，并且可能会默默地出错。 

## 方法

 直接的方法是创建一个二维板，将每个车放在上面，旋转矩阵，然后重建答案数组。 这完全符合物理操作，因此很容易证明是正确的。 但它需要存储`N * N`细胞。 什么时候`N = 100000`，这意味着`10^10`细胞，这是不可能的。 

稍微好一点但仍然不必要的方法是搜索行和列以找到每个旋转的车应该去的位置。 这避免了存储整个板，但仍然需要检查大量位置。 和`N`车，重复搜索可以到达`O(N^2)`操作，这意味着大约`10^10`在最大的情况下进行操作。 

关键的观察结果是输入已经给出了每辆车的准确坐标。 无需对空单元进行建模。 旋转公式立即给出了每个车的目的地。 一只车在`(i, a[i])`移动到`(a[i], N + 1 - i)`，所以我们只需要放置`N + 1 - i`进入答题位置`a[i]`。 

暴力方法之所以有效，是因为它重建了完整的棋盘，但完整的棋盘包含了我们不需要的信息。 排列表示已经包含所有车坐标，并且使用坐标变换将任务减少到单遍。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N²) | O(N²) | 太慢了 |
 | 最佳 | O(N) | O(N) | 已接受 |

 ## 算法演练

 1.创建一个大小为答案的数组`N`。 该数组的索引将代表旋转后的一行，存储的值将代表该行中车的列。 
2. 读取每个原始行`i`和它的车柱`a[i]`。 车位于`(i, a[i])`，所以顺时针旋转后它移动到行`a[i]`和列`N + 1 - i`。 
3. 放置`N + 1 - i`进入`answer[a[i]]`。 这直接记录旋转位置而不创建板。 
4. 按行顺序输出答案数组。 现在，每个位置恰好描述了旋转板上的一个车。 

工作原理：每个车都是独立处理的，顺时针旋转的坐标变换是精确的。 由于每个原始列都包含一个车，因此每个值`a[i]`是唯一的，这意味着每个新行都只会收到一个分配。 因此，答案数组每行包含一个有效的车位置，并且每个分配对应于正确的旋转车。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    n = int(input())
    ans = [0] * n

    for i in range(n):
        col = int(input())
        ans[col - 1] = n - i

    print(*ans)

if __name__ == "__main__":
    solve()
```数组`ans`存储旋转的板表示。 输入行和列是从 1 开始的，但 Python 数组是从 0 开始的，因此目标行`col`被转换为`col - 1`。 

在循环过程中，`i`从零开始，意味着它代表原始行`i + 1`。 新专栏是：```
N + 1 - (i + 1) = N - i
```这就是代码分配的原因`n - i`。 这避免了坐标系之间不必要的来回转换。 

分配顺序并不重要，因为每个原始列都只出现一次。 每个车写入不同的位置`ans`，因此不会覆盖之前的结果。

 ## 边缘情况

 对于单格板，算法读取行中唯一的车`1`， 柱子`1`。 它写道`1`进入`ans[0]`，所以输出仍然是：```
1
```该公式仍然有效，因为新行和新列都等于 1。 

对于对角线情况：```
3
1
2
3
```第一辆车在`(1,1)`并移动到`(1,3)`，第二个停留在`(2,2)`，第三个移动到`(3,1)`。 该算法放置`3`,`2`， 和`1`到相应的位置，产生：```
3 2 1
```这证实了减法使用`N - i`正确。 

对于一个不平凡的排列：```
4
2
4
1
3
```车的移动方式如下。 车在`(1,2)`去`(2,4)`，车在`(2,4)`去`(4,3)`，车在`(3,1)`去`(1,2)`，车在`(4,3)`去`(3,1)`。 答案位置变为：```
2 4 1 3
```实际上按行写入新列给出：```
2 4 1 3
```该实现处理了这个问题，因为每个旧列都用作唯一的目标行，因此每个车都被放置一次。
