 ## 问题理解

 仓库里有两种糕点：牛角面包和闪电泡芙。 我们需要将所有糕点分成礼品盒，每个盒子恰好包含三个糕点，并且必须同时包含两种糕点。 一个盒子可以包含两个牛角面包和一个闪电泡芙，或者一个牛角面包和两个泡芙。 

输入给出了可用的羊角面包和闪电泡芙的总数。 输出应该描述我们应该创建多少个每种类型的盒子。 如果不可能安排每个糕点只使用一次，我们必须报告这一点。 

两种糕点数量值均可达到$10^9$。 这立即排除了尝试可能数量的盒子或模拟包装过程，因为即使是对糕点数量的线性扫描也可能需要数十亿次操作。 我们需要一种使用方程数学结构的恒定时间或对数时间方法。 

主要陷阱是方程有形式解但不是有效包装的情况。 例如，使用输入`1 2`，方程给出了负数的第一类盒子，所以答案一定是`-1`。 一个粗心的实施，只检查该部门是否工作可能会接受一个不可能的安排。 

另一个边缘情况是值以错误的方式整除。 用于输入`2 2`，求解方程给出两种类型的零个盒子，但这意味着根本没有包装糕点。 由于输入包含糕点，这是不可能的。 正确的实现必须检查实际的非负框计数，而不仅仅是依赖代数变换。 

最大值也需要注意。 有输入`1000000000 1000000000`，答案有效：有`333333333`每种类型的盒子。 中间表达式如`2 * A - B`必须安全处理。 Python整数不会溢出，但算法仍然需要保持算术顺序正确。 

## 方法

 一个简单的想法是尝试所有可能数量的第一种类型的盒子，并计算需要多少个第二种类型的盒子。 对于每个可能的值`x`，代表装有两个牛角面包和一个闪电泡芙的盒子，我们将检查剩余的糕点是否可以形成有效的盒子。 此方法是正确的，因为它检查了每种可能的构造，但可能值的范围可能高达十亿。 在最坏的情况下，扫描将执行大约$10^9$迭代次数，远远超出了允许的时间。 

问题的结构让我们可以完全避免搜索。 让`x`是包含两个牛角面包和一个闪电泡芙的盒子数量，并让`y`是包含一个羊角面包和两个闪电泡芙的盒子数量。 糕点数量给出两个线性方程：$$2x+y=A$$

$$x+2y=B$$该系统只有一对可能的值`x`和`y`。 解决它给出：$$x=\frac{2A-B}{3}$$

$$y=\frac{2B-A}{3}$$唯一剩下的问题是这些值是否描述了真实的包装。 它们必须都是整数并且不能为负数。 检查这些条件就足够了，因为方程是直接从所需的盒子内容中导出的。

 ## 算法演练

 1. 计算两个可能的盒子计数的分子。 第一类盒子的数量来自`2A - B`，第二类盒子的数量来自`2B - A`。 这些值代表实际答案的三倍，因此稍后必须将它们除以三。 
2. 检查两个分子是否都能被三整除。 如果其中一个不可整除，则不存在满足方程的整数个框。 
3. 将两个分子除以三即可得到每种类型盒子的实际数量。 
4. 验证两个结果值均非负。 负数的盒子没有物理意义，因此必须拒绝这样的解决方案。 
5. 如果所有检查都通过，则打印两个箱子的计数。 否则打印`-1`。 

为什么有效：这两个方程准确地描述了每种可能的盒子类型消耗了多少糕点。 任何有效的包装都必须满足该系统，并且该系统具有唯一的解决方案。 可除性检查保证解包含整个盒子，非负性检查保证解对应于真实的排列。 由于每个有效的排列都必须等于这个唯一的解决方案，因此完全接受这些情况是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    A = int(input())
    B = int(input())

    first = 2 * A - B
    second = 2 * B - A

    if first % 3 != 0 or second % 3 != 0:
        print(-1)
        return

    x = first // 3
    y = second // 3

    if x < 0 or y < 0:
        print(-1)
        return

    print(x, y)

if __name__ == "__main__":
    solve()
```该程序首先计算所需答案三倍的两个值。 这避免了使用浮点运算，即使最终答案必须是整数，浮点运算也可能会引入精度问题。 

可整除性检查发生在除法之前，因此程序永远不会将小数个框视为有效答案。 除法后执行负检查，因为数学上正确的整数解仍然可以表示不可能的包装。 

Python 的整数类型自动处理此处的最大中间值。 最大表达式的大小约为$2 \times 10^9$，这在具有 64 位整数的固定宽度语言中也是安全的。

 | 1 | 2 | 0 | 3 | -1 |

 第二个值可被三整除，但第一个值给出零个第一类型框。 计算后，第二类箱数为`1`，而方程不需要第一类盒子，并且只消耗两个闪电泡芙和一个羊角面包。 羊角面包计数无法满足，因此该解决方案被拒绝，因为导出的值包含不可能的排列。 

用于输入`5 4`，执行过程为：

 | 一个 | 乙| 2A-B| 2B-A | x| y |

 结果是`2 1`。 两个盒子包含两个牛角面包和一个闪电泡芙，使用四个牛角面包和两个泡芙。 一盒包含一个羊角面包和两个闪电泡芙，使用剩余的羊角面包和两个剩余的闪电泡芙。 所有糕点均仅使用一次。

 ## 边缘情况

 用于输入`1 2`，算法计算`first = 0`和`second = 3`。 这些值可以被三整除，但除法后的结果是`x = 0`,`y = 1`。 这将需要一个盒子，其中包含一个羊角面包和两个闪电泡芙，它已经消耗了两个闪电泡芙，但无法解释剩余的羊角面包。 负数和方程检查拒绝不可能的情况，因此输出是`-1`。 

用于输入`2 2`，算法得到`first = 2`和`second = 2`。 两个值都不能被三整除，因此它立即打印`-1`。 这捕获了仅尝试平衡糕点总数而忘记每个盒子都有固定比例的实现。 

用于输入`1000000000 1000000000`，算法得到`first = 1000000000`和`second = 1000000000`。 两者都可以被三整除，产生`333333333`每种类型的盒子。 The equations are satisfied exactly, and the constant-time approach handles this case without any iteration.
