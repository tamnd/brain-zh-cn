 # 问题理解

 我们有一系列具有给定初始大小的细菌。 当两种细菌相遇时，只有严格较大的一种细菌才能吸收另一种细菌，从而根据吸收的量增加其自身的大小。 大小相同的细菌不能互相影响。 我们需要确定，对于每个原始细菌，是否存在某种遭遇序列使其成为唯一剩余的细菌。 

输入大小已按非降序排序。 输出是每个位置的二进制答案：`1`意味着这种特定的起始细菌有一些可能的获胜策略，而`0`意味着任何一系列的行动都不能让它独自生存。 

的约束条件为`10^5`细菌排除尝试所有可能的遭遇顺序。 可能的序列数量增长得非常快，甚至从每个起始细菌进行模拟也远远超出了可用时间。 我们需要找到一个直接从排序大小中描述获胜者的属性，从而实现几乎线性的解决方案。 

一些边缘情况很容易被忽略。 单个细菌总是获胜，因为它已经是唯一剩下的细菌了。 

例子：```
1
7
```正确的输出是：```
1
```总是将最终大小与原始最大大小进行比较的公式会错误地拒绝这种情况，因为细菌不需要打败自己。 

另一个棘手的情况是所有细菌都具有相同的大小。 

例子：```
3
5
5
5
```正确的输出是：```
0
0
0
```没有一种细菌可以吃掉另一种细菌，因为每一对细菌都具有相同的大小。 将相等的值视为自动互相帮助的解决方案将给出错误的答案。 

第三种边界情况出现重复的最大值。 

例子：```
3
1
4
4
```正确的输出是：```
0
0
0
```4号细菌可以吃掉1号细菌，变成5号细菌，但是两个4号细菌不能合作。 第一个 4 号细菌在生长之前无法消耗另一个细菌，并且在生长之后，唯一可用的生长源已被使用。 相等的最大值需要特殊处理。 

# 方法

 一种直接的方法是模拟每个起始细菌的游戏。 对于选定的细菌，我们可以反复寻找较小的剩余细菌，吸收它，并继续下去，直到所有东西都被吃掉或没有任何进展。 这是正确的，因为对于未来的获胜者来说，唯一有用的行动是从它已经可以击败的细菌中获得质量。 

问题是这个过程太慢了。 可以有`10^5`细菌，并单独测试每个可能的获胜者已经花费了成本`O(n)`工作。 此外，模拟可以执行许多吸收。 最坏的情况很容易达到`O(n^2)`操作，这大约是`10^10`最大输入的步骤。 

关键的观察结果是，获胜的细菌永远不会因为留下较小的细菌而受益。 每个较小的细菌只能使其变得更强，因此可能的获胜者可以首先吸收所有比其小的细菌。 这样做之后，它的大小是固定的，代表它在与任何更大或相等的细菌战斗之前可以达到的最强状态。 

对于一定大小的细菌`x`， 让`s`所有细菌的总和严格小于`x`。 在攻击剩余细菌之前它的最大可能大小是：`x + s`如果这个值大于所有剩余的对手，细菌就可以继续吸收一切。 如果剩下的某个对手至少有这么大，它就永远无法启动移除该对手所需的吸收链。 

因为数组是排序的，所以每个具有相同值的细菌都具有相同的一组较小的细菌，因此所有相等的值都会收到相同的答案。 我们只需要前缀和以及有关最大值的信息。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 # 算法演练

 1、针对单一细菌的情况单独处理。 它已经是赢家了，所以答案是`1`。 
2. 找出最大值以及它是否出现一次或多次。 这决定了细菌可能需要击败的最难的对手。 通常这个对手是全局最大值，但是一个独特的最大值细菌不需要打败自己，所以只需要超过第二最大值即可。 
3. 按相等值组遍历已排序的数组。 在处理一个组之前，维护小于当前组的所有值的总和。 该组中的每种细菌都具有完全相同的可用生长量。 
4. 对于每个组值`x`，计算群体中每个细菌必须击败的最大对手。 如果`x`是唯一的最大值，那个对手是第二大的值。 在所有其他情况下，它是全局最大值。 
5. 将整个组标记为获胜，当`x + sum_of_smaller_values`严格大于对手。 严格的不平等是必需的，因为相同大小的细菌不能互相消耗。 

为什么它有效：不变的是，在细菌试图击败任何更大或同等的细菌之前，最好的可能情况是它已经吸收了所有较小的细菌。 任何获胜顺序都可以重新排列，以便所有较小的吸收首先发生，因为这些吸收只会增加其规模，而不会消除未来的机会。 在达到这个最大可能的中间尺寸后，要么剩下的每个对手都较小并且细菌获胜，要么存在一个它无法击败的对手。 该算法准确地检查这个条件。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [int(input()) for _ in range(n)]

    if n == 1:
        print(1)
        return

    total_max = a[-1]
    second_max = a[-2]

    cnt_max = 1
    i = n - 2
    while i >= 0 and a[i] == total_max:
        cnt_max += 1
        i -= 1

    ans = [0] * n
    smaller_sum = 0
    i = 0

    while i < n:
        j = i
        while j < n and a[j] == a[i]:
            j += 1

        value = a[i]

        if value == total_max and cnt_max == 1:
            opponent = second_max
        else:
            opponent = total_max

        if value + smaller_sum > opponent:
            for k in range(i, j):
                ans[k] = 1

        smaller_sum += value * (j - i)
        i = j

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```输入被读入数组，因为排序顺序是问题的有用结构的一部分。 Python 整数不会溢出，因此前缀和可以安全地增长到`10^14`。 

扫描一起处理相同的值。 变量`smaller_sum`始终仅包含较小值的细菌总大小，从不包括当前组。 这个细节很重要，因为在当前细菌生长之前，同等大小的细菌不能被吃掉。 

最大值需要单独处理。 如果它出现一次，该细菌就不必打败自己，因此与最大值进行比较会错误地使这种情况不可能发生。 如果最大值出现多次，则另一个最大尺寸的细菌仍然是对手。

 # 边缘情况

 对于一种细菌，算法立即返回`1`。 

输入：```
1
7
```没有对手可以击败，因此细菌无需采取任何行动即可获胜。 

对于所有相等的值，遍历会创建一个组。 较小的总和为零，因为没有更小的细菌。 

输入：```
3
5
5
5
```可达尺寸仅为`5`，而另一种大小的细菌`5`遗迹。 由于平等不允许吸收，因此该条件失败。 

对于重复的最大值，该最大值不能使用另一个最大值作为垫脚石。 

输入：```
3
1
4
4
```有价值的群体`4`有`smaller_sum = 1`。 其可达尺寸为`5`，但对比对手依然是`4`因为存在另一个最大值。 对于单个最大值，该条件似乎成立，但此示例有两个最大值细菌，因此两者都作为一个组进行处理，而对手仍然存在`4`, 给予`5 > 4`。 该算法正确地将两人标记为获胜者。 

最后一个案例说明了为什么需要进行分组处理。 相同的值共享相同的较小总和和相同的未来可能性，因此错误地分割它们可能会产生不一致的答案。
