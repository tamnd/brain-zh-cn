 ## 解决方案
 ## 问题理解

 我们被赋予了一个`n × n`每个单元格都包含一个整数的棋盘。 对于每个单元格，我们比较两个数量。 

第一个数量是该单元格行中所有数字的总和。 第二个数量是该单元格列中所有数字的总和。 如果一个单元格的列总和严格大于其行总和，则该单元格被称为获胜。 

任务是计算有多少细胞满足这个条件。 

电路板尺寸非常小。 自从`n ≤ 30`，整个网格最多包含`30 × 30 = 900`细胞。 即使是为每个单元执行额外工作的算法仍然可以在限制内轻松运行。 这意味着我们不需要先进的优化技术，但我们仍然应该仔细考虑重复计算。 

直接实现可能会为每个单元格分别重新计算整个行总和和列总和。 每次重新计算成本`O(n)`，并且有`n²`细胞，因此总复杂度变为`O(n³)`。 和`n = 30`，这仍然足够快，因为操作总数仅约为`27,000`。 

尽管如此，问题的结构自然表明了一种更简洁的方法。 行总和和列总和可多次重复使用。 一旦我们计算一次，就可以在恒定的时间内检查每个单元格。 

有一些边缘情况可能会悄悄地破坏粗心的实现。 

考虑尽可能最小的电路板：```
1
1
```唯一的行总和是`1`，唯一的列总和也是`1`。 由于条件严格更大，所以答案是`0`。 

一个常见的错误是使用`>=`而不是`>`。 

另一个微妙的情况是每个值都相同：```
2
5 5
5 5
```每行总和等于每列总和，因此没有单元格获胜。 正确的输出是：```
0
```粗心的实现可能会意外地将相等的总和视为有效。 

一种更棘手的情况是只有某些行和列不同时：```
3
1 1 10
1 1 10
1 1 10
```行总和全部为`12`。 列总和是`3`,`3`， 和`30`。 

只有第三列产生获胜单元格，所以正确答案是：```
3
```这捕获了在计算总和时混淆行索引与列索引的实现。 

## 方法

 最直接的解决办法就是暴力破解。 对于每个细胞`(i, j)`，我们计算行的总和`i`通过迭代所有列，我们计算列的总和`j`通过迭代所有行。 如果列总和较大，我们将增加答案。 

这是可行的，因为获胜单元格的定义仅取决于这两个总和。 实现很简单并且准确地反映了问题陈述。 

问题是重复工作。 对于该行中的每个单元格，相同的行总和会重新计算一次；对于该列中的每个单元格，相同的列总和会重新计算一次。 

例如，如果`n = 30`，那么每个`900`细胞执行约`60`添加，导致大约`54,000`总体补充。 在这里这仍然是完全可以接受的，但是没有必要重复。 

关键的观察结果是行总和和列总和永远不会改变。 一旦我们计算它们一次，它们就可以被每个相关单元重复使用。 

我们可以先构建两个数组：`row_sum[i]`存储行的总和`i`。`col_sum[j]`存储列的总和`j`。 

然后每个单元格检查就变得微不足道：

 如果`col_sum[j] > row_sum[i]`，细胞获胜。 

这降低了复杂性`O(n³)`到`O(n²)`同时也使逻辑更加清晰。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 已接受 |
 | 最佳 | O(n²) | O(n) | 已接受 |

 ## 算法演练

 1.读取整数`n`和`n × n`网格。 
2. 创建数组`row_sum`尺寸的`n`用零初始化。 
3. 创建数组`col_sum`尺寸的`n`用零初始化。 
4. 遍历整个网格一次。 

对于每个细胞`(i, j)`，将其值添加到`row_sum[i]`并到`col_sum[j]`。 

这会在一次传递中计算每行总计和列总计。 
5. 初始化`answer = 0`。 
6. 再次遍历网格。 

对于每个细胞`(i, j)`， 比较`col_sum[j]`和`row_sum[i]`。 
7.如果`col_sum[j] > row_sum[i]`, 增量`answer`。 

该问题要求严格大于，而不是大于或等于。 
8. 打印`answer`。 

### 为什么它有效

 该算法依赖于一个简单的不变量：在第一次遍历之后，`row_sum[i]`等于行中每个值的总和`i`， 和`col_sum[j]`等于列中每个值的总和`j`。 

由于这些值仅根据原始网格计算一次并且之后不再修改，因此以后的每次比较都使用正确的总计。 每个单元格都会根据问题陈述中的确切条件进行独立检查，因此每个获胜单元格都会被精确计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
grid = [list(map(int, input().split())) for _ in range(n)]

row_sum = [0] * n
col_sum = [0] * n

for i in range(n):
    for j in range(n):
        row_sum[i] += grid[i][j]
        col_sum[j] += grid[i][j]

answer = 0

for i in range(n):
    for j in range(n):
        if col_sum[j] > row_sum[i]:
            answer += 1

print(answer)
```第一部分将棋盘读入二维列表。 

下一个嵌套循环同时计算行总和和列总和。 在同一遍历中更新两个数组可以避免不必要的网格遍历。 

第二个嵌套循环独立检查每个单元格。 条件使用`>`因为该语句要求列总和严格大于。 

对于像这样的小板，不需要特殊处理`n = 1`。 该逻辑自然有效，因为唯一单元格的行总和和列总和相等。 

Python 整数在这里也是完全安全的。 即使在最大的情况下，最大行或列之和也仅为`30 × 100 = 3000`。

import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())
    grid = [list(map(int, input().split())) for _ in range(n)]

    row_sum = [0] * n
    col_sum = [0] * n

    for i in range(n):
        for j in range(n):
            row_sum[i] += grid[i][j]
            col_sum[j] += grid[i][j]

    ans = 0

    for i in range(n):
        for j in range(n):
            if col_sum[j] > row_sum[i]:
                ans += 1

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

 ## 边缘情况

 考虑尽可能最小的电路板：```
1
1
```该算法计算：`row_sum = [1]`

`col_sum = [1]`对于唯一的单元格，比较变为`1 > 1`，这是错误的。 该算法正确打印：```
0
```这证实了平等不被计算在内。 

现在考虑一个每个数字都相同的棋盘：```
2
5 5
5 5
```行总和变为`[10, 10]`，并且列总和也变为`[10, 10]`。 

每次比较都是`10 > 10`，这是错误的。 没有细胞被计数，所以答案是：```
0
```这个案例验证了实现没有意外使用`>=`。 

最后，考虑一个具有主导列的情况：```
3
1 1 10
1 1 10
1 1 10
```该算法计算：`row_sum = [12, 12, 12]`

`col_sum = [3, 3, 30]`对于每一行，只有第三列满足`30 > 12`。 

正好计数了三个单元格，因此输出为：```
3
```这确认了行索引和列索引已正确处理，并且总和在所有单元格中一致地重用。
