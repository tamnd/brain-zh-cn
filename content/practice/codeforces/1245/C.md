 ## 解决方案
 ## 问题理解

 我们收到一根据称是由一台稍微损坏的书写机生产的绳子。 机器通常将每个口头字母单独打印，但两个特殊字母的行为不同：如果用户说`w`，机器写入`uu`，如果用户说`m`，它写道`nn`。 所有其他字母均按原样打印。 

我们得到一个最终的书面字符串，并被要求计算在这些规则下有多少原始的口头字符串可以产生它。 

换句话说，我们试图将给定的字符串分解为段，其中每个`u`可能来自真实的`u`或来自隐藏的`w`，以及每一个`n`可能来自真实的`n`或来自隐藏的`m`。 任务是计算所有有效的分解。 

输入长度最大可达100,000。 任何尝试枚举所有解释或进行指数分支的解决方案都会立即失败，因为即使是一小部分重复字符，例如`uuuuuu...`会爆炸成指数组合。 这迫使采用线性或近线性动态规划方法。 

一个微妙的边缘情况是运行中的无效字符会破坏所有可能性。 例如，如果字符串包含除`u`,`n`,`w`， 或者`m`，这仍然没问题，因为这些字母是固定的，但如果解释强制错误地分割，某些片段可能变得不可能。 更具体地说，考虑`"amanda"`。 这封信`m`在原始语言中总是会产生`"nn"`，所以一个独立的`m`在输出中永远不可能存在。 任何情况的发生`m`输出字符串中的 立即杀死所有有效的解释，因为没有源字母产生单个`m`。 

另一个重要的情况是短期运行。 例如`"u"`仅有一种解释，但是`"uu"`有两个：要么`u u`或者`w`。 为了`"uuu"`我们已经需要重复，因为重叠的位置`w`创建依赖关系。 

## 方法

 强力解释试图将每个位置视为来自普通字母或合并转换的一部分。 这很快就会成为一个回溯问题，其中每次运行相同的字符`u`或者`n`每一步的决策都会加倍。 对于一个长度的运行`k`，分段数量对应于斐波那契式增长，但朴素枚举仍会显式分支，导致指数复杂性。 

关键的观察是只有两个字母引入歧义，并且两个歧义都是局部的：`w → uu`和`m → nn`。 这意味着歧义仅出现在连续运行中`u`或者`n`。 其他一切都是一对一固定的。 

因此可以线性处理字符串，将其压缩为最大连续运行。 对于任何运行`u`长度`k`，我们计算有多少种方法可以将其分割成大小为 1 或 2 的片段，因为每个片段对应于一个文字`u`或隐藏的`w`。 这同样适用于运行`n`。 

这正是每个游程长度上的斐波那契 DP 乘以独立段。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最佳 DP（运行 + 斐波那契）| O(n) | O(n) 或 O(1) | 已接受 |

 ## 算法演练

 我们处理该字符串并将其压缩为具有相同字符的连续块。 

1. 从左到右扫描字符串并确定相同字符的最大运行次数。 每次运行都是独立处理的，因为没有转换跨越不同的字符边界。 
2.如果我们遇到一个角色`m`或者`w`在最终的字符串中，我们立即返回 0。这是因为两者都不是`m`也不`w`可以在输出中显示为单个打印字符； 它们总是扩展为两个字符序列。 
3. 对于每次运行`u`与长度`k`，计算将其划分为大小为 1 或 2 的段的方法数。大小为 1 的段对应于文字`u`，一个 size-2 的段对应一个隐藏的`w`。 
4. 对于每次运行`n`与长度`k`，计算相同类型的分区计数，因为`n`可以来自`n`或来自`m`。 
5. 将每次运行的贡献乘以全局答案模$10^9+7$。 
6. 使用斐波那契式 DP，其中`dp[i]`表示覆盖一段长度的方法数量`i`。 过渡是`dp[i] = dp[i-1] + dp[i-2]`，因为最后一段的大小要么是大小 1，要么是大小 2。 

### 为什么它有效

 每个有效的解释都唯一对应于每个最大的平铺`u`或者`n`分段成长度为 1 或 2 的图块。这些图块在分段之间是独立的，因为不同的字符在解释中不能重叠。 递归精确地计算了拆分或合并相邻字符的所有二元选择，并且没有配置被计算两次，因为每个平铺恰好对应于一次分解`u`和`w`（或者`n`和`m`）。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

s = input().strip()

# invalid characters that cannot appear in output
# since m and w are always expanded, they never appear alone
for ch in s:
    if ch == 'm' or ch == 'w':
        print(0)
        sys.exit(0)

n = len(s)

# precompute fibonacci up to n
dp = [0] * (n + 1)
dp[0] = 1
if n >= 1:
    dp[1] = 1

for i in range(2, n + 1):
    dp[i] = (dp[i - 1] + dp[i - 2]) % MOD

ans = 1

i = 0
while i < n:
    j = i
    while j < n and s[j] == s[i]:
        j += 1
    length = j - i

    if s[i] == 'u' or s[i] == 'n':
        ans = (ans * dp[length]) % MOD

    i = j

print(ans)
```该代码首先拒绝涉及以下不可能的情况`m`或者`w`。 然后它预先计算斐波那契数，因为每次运行长度`k`减少到平铺计数`dp[k]`。 该字符串被扫描一次以提取运行，并且每次运行都会对答案产生乘法贡献。 

一个常见的实施陷阱是忘记运行是独立的。 另一个问题是混淆了哪些字符是有效的单例。 仅有的`u`和`n`模棱两可； 其他一切都以一种方式做出贡献。

## 复杂度分析

## 测试用例```python
import sys, io

MOD = 10**9 + 7

def solve():
    s = input().strip()
    for ch in s:
        if ch == 'm' or ch == 'w':
            print(0)
            return

    n = len(s)
    dp = [0] * (n + 1)
    dp[0] = 1
    if n >= 1:
        dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = (dp[i-1] + dp[i-2]) % MOD

    ans = 1
    i = 0
    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1
        length = j - i
        if s[i] in ('u', 'n'):
            ans = (ans * dp[length]) % MOD
        i = j

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    solve()
    return sys.stdout.getvalue().strip()

# provided samples
assert run("ouuokarinn\n") == "4"

# custom cases
assert run("banana\n") == "1"
assert run("u\n") == "1"
assert run("uu\n") == "2"
assert run("m\n") == "0"

 ## 边缘情况

 单个`m`或者`w`输入中立即强制答案为零，因为没有有效的原始字符串可以产生独立的`m`或者`w`。 该算法通过在任何 DP 工作之前提前终止来处理此问题。 

长期运行的`u`例如`"uuuuuu"`测试斐波那契预处理是否正确地扩大了分割组合。 DP 确保每个附加字符只会线性增加复杂性。 

混合字符串如`"uunnnnuu"`测试运行的独立性。 每个块都是单独处理的，乘法步骤确保跨块组合在没有交互的情况下正确计数。
