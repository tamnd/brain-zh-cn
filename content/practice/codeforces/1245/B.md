 ## 解决方案
 ## 问题理解

 我们看到了鲍勃所玩的一系列石头剪刀布的动作。 除此之外，爱丽丝还有固定的动作清单：她必须在所有回合中准确地玩出指定数量的石头、剪刀、布。 

目标是决定爱丽丝是否可以安排她的动作，以便她赢得至少一半的回合（向上取整），因为她提前知道鲍勃的整个序列。 单轮胜利取决于标准 RPS 规则：石头胜剪刀，剪刀胜布，布胜石头。 

如果存在这样的策略，我们还必须构造一个有效的爱丽丝移动序列，以实现所需的获胜次数，同时尊重每次移动的确切计数。 

限制很小：最多 100 个测试用例，每个游戏最多 100 轮。 这立即排除了每个测试用例中任何比线性或二次更重的东西，但更重要的是，它表明贪婪的构造或简单的动态编程就足够了。 不需要指数搜索或回溯，因为状态空间很小但结构化。 

当幼稚的策略试图在不考虑资源耗尽的情况下“局部最大化胜利”时，就会出现微妙的失败案例。 例如，如果爱丽丝贪婪地尽早使用所有布棋来击败石头，她可能稍后会面对剪刀，但已经没有剪刀了，从而失去了不同分布本可以保留的潜在胜利。 另一种失败模式是在取得一些胜利后任意填充动作，意外地违反了精确的计数要求或不必要地减少了胜利。 

关键的挑战是同时平衡两个约束：在已知序列下最大化胜利并尊重每种移动类型的固定配额。 

## 方法

 暴力解决方案将尝试爱丽丝的多组动作的所有可能排列，并计算每种排列对鲍勃的胜利。 即使对于单个测试用例，这也大约是$\frac{n!}{a!b!c!}$，即使对于$n = 20$。 这是完全不可行的。 

关键的观察是，除了步数有限之外，每个位置都是独立的。 我们不需要考虑全局排列； 相反，我们可以根据是否可以使用获胜的棋步来贪婪地决定每个位置。 

在每个指数上，鲍勃的举动准确地确定了一个能够产生胜利的最佳反击。 如果我们的配额中仍然有可用的走法，那么使用它总是最佳的，因为现在使用获胜的走法永远不会减少未来的机会，除非通过消耗有限的资源。 由于每一步棋都只对一个位置有贡献，因此这种贪婪的分配最大化了总体上可实现的胜利数量。 

一旦所有获胜机会都用尽，剩余的位置可以使用剩余的动作任意填补，同时保留计数。 

这将问题简化为在容量限制下构建最大获胜分配，然后检查该最大值是否满足所需的阈值。

 ## 算法演练

 让$k = \lceil n/2 \rceil$，所需的最少胜利次数。 

1. 对于每个测试用例，请阅读$n$, 计数$a, b, c$，和鲍勃的绳子。 

我们保留一个结果数组`ans`最初为空并跟踪剩余计数。 
2. 第一遍：尽可能分配获胜的棋步。 

对于每个位置$i$:

 - 如果鲍勃玩“R”，爱丽丝通过玩“P”获胜（如果还有 P）。 
- 如果 Bob 玩“P”，Alice 则通过玩“S”获胜（如果还有 S）。 
- 如果 Bob 玩“S”，Alice 则通过玩“R”获胜（如果还有 R）。 

我们立即贪婪地分配这些获胜的棋步并减少相应的配额。 

理由是，每项此类任务都是绝对有益的，因此推迟它只会冒浪费机会的风险。 
3. 完成这一关后，计算取得了多少场胜利。 
4. 如果胜利已经至少$k$，我们继续使用剩余的动作任意填充所有剩余的空位置$a, b, c$。 
5. 如果胜利少于$k$，我们立即输出“NO”，因为即使是最优的贪心策略也无法达到阈值。 
6. 否则，输出“YES”，后跟构造的序列。 

### 为什么它有效

 每个位置最多只有一招可以保证获胜。 贪婪地分配此类移动永远不会与另一个位置发生冲突，因为移动仅受全局计数的约束，而不受位置依赖性的约束。 由于每项获胜任务都会严格增加总分，并且只消耗一个单位的有限资源，因此推迟获胜并不能增加最终的获胜次数。 因此，这个贪婪的过程会产生最大可实现的获胜次数。 如果这个最大值低于阈值，则任何有效的重新排列都不会成功。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a, b, c = map(int, input().split())
        s = input().strip()

        ans = [''] * n
        wins = 0

        # First pass: take all guaranteed wins
        for i, ch in enumerate(s):
            if ch == 'R' and b > 0:
                ans[i] = 'P'
                b -= 1
                wins += 1
            elif ch == 'P' and c > 0:
                ans[i] = 'S'
                c -= 1
                wins += 1
            elif ch == 'S' and a > 0:
                ans[i] = 'R'
                a -= 1
                wins += 1

        need = (n + 1) // 2
        if wins < need:
            print("NO")
            continue

        # Fill remaining slots
        for i in range(n):
            if ans[i] == '':
                if a > 0:
                    ans[i] = 'R'
                    a -= 1
                elif b > 0:
                    ans[i] = 'P'
                    b -= 1
                else:
                    ans[i] = 'S'
                    c -= 1

        print("YES")
        print("".join(ans))

if __name__ == "__main__":
    solve()
```仅当有保证获胜时，第一个循环才会积极消耗移动资源。 这是决定胜利的唯一地方。 第二个循环纯粹是一个填充阶段，尊重剩余配额而不影响已经固定的结果。 

一个常见的错误是尝试在第一次传递期间同时平衡所有三种移动类型。 这是不必要的，因为可行性检查仅取决于是否可以捕获足够的获胜机会，而不是平均分配损失。

 ## 边缘情况

 一种边缘情况是鲍勃的序列严重偏向于一种移动类型，但爱丽丝缺乏足够的计数器来做出相应的获胜反应。 例如，如果鲍勃玩了很多“R”，但爱丽丝只有很少的“P”，则贪婪循环会简单地跳过这些位置并将它们留待以后填充。 该算法自然会在不破坏计数的情况下处理这个问题，因为它从不强制执行不可用的获胜动作。 

另一种情况是，爱丽丝的计数完全正确，但获胜机会却很分散。 即使有可能获胜，它们也可能不会出现在比赛的早期。 贪婪扫描仍然捕获它们，因为它不依赖于线性遍历之外的位置排序，并且每个机会都是独立评估的。 

最后一种情况是所需的胜利次数恰好等于可实现的最大胜利次数。 该算法仍然有效，因为它首先构造完整的最大获胜分配，并且仅拒绝严格不可行的情况，即使该最大值也不够。
