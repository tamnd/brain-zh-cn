 ## 解决方案
 ## 问题理解

 我们看到一系列敌人沿着伊吉的逃跑路线排列。 每个敌人都有一定的生命值，伊吉一开始也有固定的生命值。 她必须将每个敌人的生命值一一降低至零或以下，同时绝不让自己的生命值降至零或以下。 

为了击败敌人，伊基有两种攻击模式。 每个敌人最多可以使用第一种模式一次。 它会对敌人造成固定数量的伤害，但也会让伊吉损失固定数量的生命值。 第二种模式可以使用任意多次，每次使用都会对敌人造成一些伤害，同时也会消耗伊基的生命值。 

任务是确定是否存在一种方法来选择对每个敌人使用多少次无限攻击以及是否使用单次攻击，以便击败所有敌人并且伊基的生命值始终保持严格的正值。 

这些限制迫使我们走向$O(M)$或者$O(M \log M)$解决方案，因为最多可以有$10^5$敌人。 任何尝试以幼稚的方式独立模拟每个敌人的攻击组合的解决方案都会很快爆炸，因为对于每个敌人，我们原则上可以选择使用特殊攻击或不使用特殊攻击，然后选择多种冲锋攻击组合。 如果处理不当，这会导致指数或至少二次行为。 

天真的推理的一个微妙的失败案例是通过始终最大化局部伤害效率来独立对待每个敌人。 例如，每当每次攻击看起来高效时总是使用拇指尖刺可能会失败，因为它可能会浪费对弱敌人的最佳固定伤害选项，而让强大的敌人在以后变得过于昂贵。 

当冲锋攻击在伤害效率和每次伤害的生命值方面都严格优于拇指尖刺时，就会出现另一种棘手的边缘情况，但拇指尖刺仍然很重要，因为它提供一次性爆发，可以显着减少大型敌人的冲锋使用次数。 

## 方法

 关键的观察结果是，除了总剩余生命值外，每个敌人都是独立的。 对于每个敌人，我们需要决定如何最小化将其 HP 降至零所需的生命值成本，因为我们可以选择应用一次性奖励攻击。 

如果我们忽略拇指尖刺，每个敌人$a_i$需要$\lceil a_i / Q_1 \rceil$冲锋攻击，成本计算$Q_2 \cdot \lceil a_i / Q_1 \rceil$健康。 

现在介绍一下拇指钉。 如果我们对敌人使用它，其生命值会有效减少$P_1$，所以剩余HP变为$\max(0, a_i - P_1)$。 这减少了该敌人所需的冲锋攻击次数。 但是，我们支付额外的固定费用$P_2$每次使用一次。 

因此，对于每个敌人，我们在两种成本之间进行选择：纯粹的冲锋成本，或我们花费的混合成本$P_2$加上HP减少后的充电成本$P_1$。 

这将问题简化为针对每个敌人计算这两个值的最小值，并对所有敌人求和。 唯一剩下的问题是 Iggy 的初始生命值是否足够。 

暴力方法将尝试每个敌人的两种选择并单独模拟冲锋攻击，从而导致$O(M \cdot a_i)$在最坏的情况下，这是不可行的，因为$a_i$可以达到$10^9$。 

关键的简化是认识到成本结构是可加的并且与每个敌人无关。 一旦我们确定了敌人的选择，其最佳内部策略就是确定性的：始终使用冲锋攻击，可以选择在单个尖峰之前进行攻击。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(M \cdot \max a_i)$|$O(1)$| 太慢了|
 | 最佳|$O(M)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 对于每个敌人，计算仅使用冲锋攻击击败它的成本。 这是所需的命中次数乘以每次命中的生命值。 命中次数是根据敌人生命值的上限除以计算得出的$Q_1$。 
2. 对于同一个敌人，计算如果我们仅使用一次拇指钉的替代成本。 首先减少敌方HP$P_1$，但不低于零，然后计算剩余HP需要多少次冲锋攻击，并加上固定成本$P_2$。 这说明了这样一个事实：尖峰只有在真正减少冲锋攻击次数时才有用。 
3. 取两个计算成本中的最小值。 考虑到问题的全球结构，这代表了孤立地击败敌人的最佳方式。 
4. 将所有敌人的最小成本相加。 这一总额是扫清道路所需的最低可能卫生支出。 
5. 检查总成本是否严格小于初始健康状况$N$。 如果是，则输出YES； 否则输出NO。 

### 为什么它有效

 关键的不变量是每个敌人的最佳策略仅取决于自己的生命值，而不取决于其他敌人的决策。 任何攻击序列都可以重新排列，以便对一个敌人的所有行动都是连续的，而不改变总成本，因为攻击不会在敌人之间相互作用。 因此，独立地最小化每个敌人的成本并求和会产生全局最优值。 除了总生命值之外，没有任何耦合约束，总生命值在敌人之间呈线性和累加关系，因此局部最优意味着全局最优。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ceil_div(a, b):
    return (a + b - 1) // b

def solve():
    N, M = map(int, input().split())
    P1, P2 = map(int, input().split())
    Q1, Q2 = map(int, input().split())
    arr = list(map(int, input().split()))
    
    total_cost = 0
    
    for a in arr:
        # cost using only charge attacks
        hits = ceil_div(a, Q1)
        cost_charge = hits * Q2
        
        # cost using spike once + charge
        reduced = max(0, a - P1)
        hits2 = ceil_div(reduced, Q1)
        cost_spike = P2 + hits2 * Q2
        
        total_cost += min(cost_charge, cost_spike)
    
    print("YES" if total_cost < N else "NO")

if __name__ == "__main__":
    solve()
```实施直接遵循导出的成本模型。 上限除法辅助函数避免了浮点运算，保证了生命值不能被攻击力整除时的正确性。 每个敌人都会在一次传递中独立处理。 

一个微妙的实现细节是使用`max(0, a - P1)`划分之前。 如果没有这个，负 HP 可能会由于整数除法行为而错误地减少所需的冲锋攻击次数。 另一个关键点是使用严格比较`total_cost < N`，因为在受到所有伤害后，Iggy 的生命值必须严格保持在零以上。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import ceil
    input = sys.stdin.readline

    N, M = map(int, input().split())
    P1, P2 = map(int, input().split())
    Q1, Q2 = map(int, input().split())
    arr = list(map(int, input().split()))
    
    def ceil_div(a, b):
        return (a + b - 1) // b
    
    total = 0
    for a in arr:
        cost1 = ceil_div(a, Q1) * Q2
        reduced = max(0, a - P1)
        cost2 = P2 + ceil_div(reduced, Q1) * Q2
        total += min(cost1, cost2)
    
    return "YES\n" if total < N else "NO\n"

# provided sample
assert run("8 3\n5 2\n3 1\n5 8 6\n") == "YES\n"

# minimum input
assert run("1 1\n1 1\n1 1\n1\n") == "NO\n"

# spike useless case
assert run("20 2\n10 100\n1 1\n10 10\n") == "NO\n"

# spike dominates case
assert run("50 2\n9 1\n5 10\n20 20\n") == "YES\n"

# large HP single enemy
assert run("100 1\n50 1\n10 1\n1000000000\n") == "YES\n"

 ## 边缘情况

 当尖峰将生命值降低到零以下时，就会出现一种边缘情况。 在这种情况下，所有冲锋攻击都会消失，只有尖峰成本很重要。 例如，如果$a_i \le P_1$，那么减少的HP就为零，成本就是$P_2$。 该算法通过以下方式正确处理这个问题`max(0, a - P1)`然后零电荷击中。 

另一个边缘情况是冲锋攻击效率极低，但尖峰攻击也很昂贵。 例如，如果$Q_1 = 1$和$Q_2$较大时，充电成本与HP成线性关系，而尖峰仅提供有限的减少。 该算法仍然正确地计算两个表达式并避免任何贪婪的误用。 

最后一个边缘情况是所有敌人都相同且很大。 该算法不依赖于排序或顺序，因此通过独立的每个敌人评估自然地处理重复值。
