 ## 解决方案
 ## 问题理解

 每个鸡蛋都有两种独立的提取价值的方式：煎炸它给出一个分数，炒它给出另一个分数，跳过它给出零贡献。 约束条件是伊万不能自由选择所有正选项。 他最多仅限于$F$煎鸡蛋最多$S$所有选择的炒鸡蛋。 每个鸡蛋只能以一种方式使用，因此这是两个全局容量限制下每个项目的分区决策。 

任务是将每个鸡蛋分配到三个状态之一，同时尊重两个容量上限，同时最大化收集的总价值。 由于值可能为负，因此最好完全跳过一些鸡蛋，即使在允许的容量范围内，最好不要使用插槽。 

输入大小可达$N = 10^4$， 尽管$F + S \le 100$。 这种组合是关键的结构线索：虽然物品很多，但“付费槽位”的数量却极少。 任何试图在大型状态空间中跟踪每个鸡蛋决策的解决方案都会遇到困难，但任何将容量视为主要维度的解决方案都可以保持高效。 一个天真的$O(N \cdot F \cdot S)$DP 已经处于可接受的范围，但更仔细的减少或贪婪的优化变得有吸引力。 

一个微妙的边缘情况来自负值。 如果所有值均为负数，则正确答案为零，因为允许跳过所有鸡蛋。 当一个类别被禁用时，会出现另一种边缘情况，例如$F = 0$，这会迫使所有选定的鸡蛋打乱或跳过，从而改变过渡的结构。 

## 方法

 一种直接的方法是独立考虑每个鸡蛋并尝试所有可能性：煎它（如果容量剩余），炒它（如果容量剩余），或者跳过它。 这自然会导致对项目和剩余容量的动态规划公式。 让$dp[i][f][s]$代表处理完第一个后的最大满意度$i$鸡蛋与$f$炸槽和$s$已使用的加扰插槽。 对于每个鸡蛋，我们尝试三种转换。 这是正确的，因为它探索了所有有效的作业。 

问题是$N = 10^4$，所以即使是单层 DP$F \cdot S \le 100$仍然暗示着周围$10^6$状态，每个状态都会经过三种选择，给出大约$3 \cdot 10^6 \cdot 10^4$操作，这太慢了。 

关键的观察结果是，鸡蛋的顺序在超出容量限制的情况下并不重要。 每个鸡蛋独立贡献，我们选择最多$F + S \le 100$所有鸡蛋的总“任务”。 这改变了视角：我们不是首先迭代鸡蛋，而是迭代我们决定总共吃多少个煎蛋和炒鸡蛋，然后选择哪些鸡蛋最能填充这些槽。 

我们可以将其重新解释为选择最多$F$“炸池”项目及最多$S$“乱序池”的物品，但有每个物品只能使用一次的限制。 标准技巧是在小容量空间内保持 DP 的同时逐个处理鸡蛋。 因为容量很小，所以我们可以买一个二维背包，其中每个物品都可以进入三种状态之一，并且我们根据容量反向更新 DP 以避免重复使用。 

这是有效的，因为虽然$N$很大，每个鸡蛋只贡献两个潜在收益，并且容量状态空间足够小，可以有效吸收所有转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举赋值| 指数| O(1) | O(1) | 太慢了 |
 | 3D DP 覆盖物品、油炸、炒 | O(NFS) | O(NFS) | 太慢了 |
 | 优化的2D背包DP | O(NFS) | O(FS) | 已接受 |

 ## 算法演练

 我们维护一个 DP 表，其中$dp[f][s]$代表在考虑鸡蛋的某些前缀后，准确使用可实现的最佳总满意度$f$油炸选择和$s$混乱的选择。 

1. 将所有 DP 状态初始化为非常负的值，除了$dp[0][0] = 0$。 这代表从没有选择鸡蛋且满意度为零开始。 
2.将每个鸡蛋一颗一颗地处理。 
3. 对于每个鸡蛋都有值$f_i$（油炸）和$s_i$（扰乱），我们按照容量的相反顺序更新 DP 表。 
4. 对于每对$(f, s)$，我们考虑不使用鸡蛋，保留$dp[f][s]$不变。 
5.如果$f > 0$，我们考虑将这个鸡蛋分配给油炸，从$dp[f-1][s] + f_i$。 这代表消耗一个油炸槽并获得其油炸满足感。 
6.如果$s > 0$，我们考虑将这个鸡蛋分配给炒蛋，从$dp[f][s-1] + s_i$。 这代表消耗一个加扰时隙。 
7. 我们在每个州的这些选择中选取最大值。 
8. 处理完所有鸡蛋后，答案是所有鸡蛋中的最大值$dp[f][s]$为了$0 \le f \le F$,$0 \le s \le S$，因为我们不需要完全使用所有插槽。 

对容量的反向迭代至关重要。 如果没有它，单个鸡蛋可能会在同一迭代中多次重复使用，这将违反每个鸡蛋最多使用一次的约束。 

### 为什么它有效

 在处理鸡蛋子集后的任何时候，每个 DP 状态都会使用每个鸡蛋最多一次对最佳可实现值进行编码。 处理新鸡蛋时，转换仅从尚不包含该鸡蛋的状态延伸。 因为我们向后迭代容量，所以任何状态更新都不能在同一迭代中反馈到同一个蛋的另一个更新中。 这保留了每个鸡蛋最多贡献一次的不变量。 

DP 在容量限制下有效地探索鸡蛋的所有有效分配为三类，但将指数分配空间压缩为纯粹由资源使用定义的多项式状态空间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

NEG = -10**30

def solve():
    N, F, S = map(int, input().split())
    
    dp = [[NEG] * (S + 1) for _ in range(F + 1)]
    dp[0][0] = 0

    for _ in range(N):
        f_i, s_i = map(int, input().split())

        for f in range(F, -1, -1):
            for s in range(S, -1, -1):
                best = dp[f][s]

                if f > 0 and dp[f - 1][s] != NEG:
                    best = max(best, dp[f - 1][s] + f_i)

                if s > 0 and dp[f][s - 1] != NEG:
                    best = max(best, dp[f][s - 1] + s_i)

                dp[f][s] = best

    ans = 0
    for f in range(F + 1):
        for s in range(S + 1):
            ans = max(ans, dp[f][s])

    print(ans)

if __name__ == "__main__":
    solve()
```DP 表使用非常负的值进行初始化，以区分无法到达的状态和有效的低分配置。 零仅分配给空选择。 

嵌套循环向后迭代$f$和$s$确保每个状态层的每个鸡蛋都被精确处理一次。 更新计算将鸡蛋煎或炒是否可以改善当前的最佳状态。 对所有状态的最终扫描是必要的，因为未使用的容量是允许的并且有时是最佳的。

 ## 边缘情况

 一个关键的边缘情况是容量为零时。 在这种情况下，不可能进行选择，因此必须跳过每个鸡蛋。 DP 开头为$dp[0][0] = 0$并且永远不允许转换到无效状态，因此即使所有值都很大且为正值，它自然会输出零。 

另一种情况是所有值均为负数。 DP 仍可能尝试降低分数的转换，但所有状态的最终最大值包括空选择，保留零作为最佳答案。 例如，用一个鸡蛋$(-5, -10)$和$F = S = 1$，DP 短暂考虑了负面状态，但最终保留了$dp[0][0] = 0$最好的。 

一种更微妙的情况是，对于同一个鸡蛋，一个类别支配另一个类别。 DP 确保了排他性，因为它仅从先前的状态进行转换，而不结合同一个蛋的两种选择。 这可以防止重复计算，并确保每个鸡蛋最多贡献一个值，完全匹配问题约束。
