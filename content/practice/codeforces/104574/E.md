 ## 解决方案
 ## 问题理解

 我们有一副固定的 52 张牌，其中每个位置包含一个从 1 到 13 的数字，每个值恰好出现四次。 其中，值为 1 的牌是 A，是唯一对获胜至关重要的牌。 

甲板上的一次操作就是一次完美的步枪洗牌。 这副牌被分成大小为 26 的两半。然后，将这两半按照固定的模式交错，形成洗牌牌：上半的第一张牌，下半的第一张牌，上半的第二张牌，下半的第二张牌，依此类推。 此操作定义了位置的确定性重新排列，因此重复应用它会产生一系列牌组排列。 

我们可以多次应用此随机播放。 问题是是否存在一定次数的洗牌，之后所有四张 A 都位于位置 1 到 26 内。 

约束很小且固定：牌组大小始终为 52，并且没有多个测试用例。 这立即排除了对常数或非常小的多项式因子之外的渐近优化的任何需要。 排列结构的直接模拟是可行的，但独立地强制所有可能的洗牌是不可行的，因为洗牌重复排列循环而不是探索任意重新排列。 

一个微妙的边缘情况是，条件不是各个 A 独立进入上半场，而是他们在相同次数的洗牌后同时到达上半场。 例如，每张 A 可能会以不同的洗牌计数出现在上半场，但不存在所有四个都同时出现在上半场的单一洗牌计数。 这种区别导致天真的独立推理失败。 

另一个边缘情况是假设因为洗牌“混合得很好”，所以每个配置都是可达的。 这是错误的，因为该操作是固定排列，因此系统在不相交的位置循环内演化。 

## 方法

 一种简单的方法是反复模拟洗牌，并在每一步后检查所有四张 A 是否都在上半场。 由于排列的周期最多为通过重复应用固定排列可达到的不同排列的数量，因此我们可以模拟最多 52 个步骤并每次进行检查。 原则上这是可行的，因为在最多 52 个应用程序之后，配置必须在 52 个元素的系统中重复，但它在概念上是浪费的，并且不会暴露问题的结构。 

关键的观察是洗牌是位置上的固定排列。 每个位置都属于一个循环，重复应用随机播放只会旋转这些循环内的元素。 每个王牌独立地沿着自己的循环移动，但所有循环都通过相同数量的应用洗牌来同步。 

所以问题就变成了：我们有四个起始位置，每个位置都位于某个循环中。 我们想知道是否存在一个时间步长 k，使得对于每张 A，其在时间 k 时的位置位于这副牌的前半部分。 

在每个循环内，我们可以通过循环中的索引来标记位置。 每次我们应用洗牌时，我们都会沿着循环前进一步。 因此，对于每个王牌，我们可以预先计算哪些循环索引对应于上半场的位置。 然后，每个 ace 贡献一组以其循环长度为模的有效残基。 我们需要一个同时满足所有四个条件的 k 值。 由于循环长度很小且总和为 52，因此所有相关循环长度的最小公倍数也小到足以进行暴力破解。 

这减少了从排列搜索到交叉周期约束的问题。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 大量洗牌的全牌模拟 | O(52·52)| O(52) | 已接受但没有必要 |
 | 循环分解+模块化检查| O(52 + LCM 搜索) | O(52) | 已接受 |

 ## 算法演练

 ### ## 算法演练

 1. 构造由位置 1 到 52 上的一次洗牌引起的排列 P。这意味着计算单个 riffle 交错后每个索引移动的位置。 此步骤将洗牌过程转变为索引上的纯排列问题。 
2. 将排列 P 分解为不相交的循环。 每个位置都属于一个循环，重复的洗牌对应于在该循环内向前行走。 
3. 对于每个循环，记录我们遍历一次时遇到的位置序列。 该序列表示在该循环中开始的元素随着时间的推移将占据的所有可能位置。 
4. 对于一个循环中的每个位置，确定它是否位于这副牌的前半部分。 将周期中的相应指数标记为处于目标区域的“好时光”。 
5. 对于每个 A，找到其起始循环以及该循环内的起始索引。 从该周期中标记的“好时间”中，收集所有残数 k，使得经过 k 次洗牌后，ace 位于上半场。 
6. 现在寻找一个同时满足所有四个 ace 的公共 k。 这是通过尝试从 0 到所有涉及的循环长度的最小公倍数的 k，检查当时每个 A 是否处于有效位置来完成的。 

### 为什么它有效

 洗牌不会在循环之间混合元素，因此每张卡牌都会在固定的循环结构内独立演化。 ace 之间的唯一耦合是要求全局应用相同数量的洗牌步骤。 这将问题转化为基于每个周期派生的模块化算术约束的同步条件。 

因为每个状态都以等于其循环长度的周期重复，所以将注意力限制在组合系统的一个完整周期上，保证了 A 相对于前半部分的每一种可能的对齐都被恰好观察到一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_perm():
    # permutation on positions 0..51
    # new order: a0,a26,a1,a27,... in 0-indexed form
    p = [0] * 52
    for i in range(26):
        p[i] = 2 * i
        p[i + 26] = 2 * i + 1
    return p

def solve():
    a = list(map(int, input().split()))
    
    p = build_perm()

    # find cycles of permutation on positions
    vis = [False] * 52
    cycle_id = [-1] * 52
    cycles = []

    for i in range(52):
        if vis[i]:
            continue
        cur = []
        x = i
        while not vis[x]:
            vis[x] = True
            cycle_id[x] = len(cycles)
            cur.append(x)
            x = p[x]
        cycles.append(cur)

    # locate ace positions (value == 1)
    aces = [i for i, v in enumerate(a) if v == 1]

    # precompute position-in-cycle index
    pos_in_cycle = {}
    for cid, cyc in enumerate(cycles):
        for idx, node in enumerate(cyc):
            pos_in_cycle[node] = (cid, idx)

    # for each ace, compute allowed k residues
    mods = []
    lens = []

    for pos in aces:
        cid, idx = pos_in_cycle[pos]
        cyc = cycles[cid]
        L = len(cyc)
        good = set()
        for t in range(L):
            if cyc[t] < 26:  # first half
                good.add(t)
        mods.append(good)
        lens.append(L)

    L = 1
    for l in lens:
        L = (L * l) // __import__("math").gcd(L, l)

    for k in range(L):
        ok = True
        for pos in aces:
            cid, idx = pos_in_cycle[pos]
            cyc = cycles[cid]
            Lc = len(cyc)
            if cyc[(idx + k) % Lc] >= 26:
                ok = False
                break
        if ok:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```该代码首先将洗牌转换为索引上的排列。 然后它提取循环，以便重复的洗牌成为每个循环上的模块化算术。 每个 ace 都在其循环中独立跟踪，最后的循环检查是否存在一个全局步数，其中所有 ace 都落在有效位置。 

一个微妙的实现细节是使用循环索引，而不是对整个数组重复应用排列。 这避免了多余的工作并使周期结构变得明确。 第二个关键细节是计算循环长度的最小公倍数以安全地限制搜索空间。

 ## 边缘情况

 一个重要的边缘情况是当 A 处于完全包含在下半场的循环中时。 在这种情况下，其循环永远不会与位置 1 到 26 相交，因此该算法对于任何配置都会正确生成“否”。 

另一种边缘情况是所有四张 A 都位于同一个循环中。 然后，问题就简化为检查该周期中是否存在单个索引，其中所有四个事件都在前半部分重合。 模块化检查自然地处理了这一问题，因为所有约束都崩溃为一个周期对齐条件。 

最后一个微妙的情况是周期长度不同时，例如，一个 A 在长度为 6 的周期中移动，另一个在长度为 8 的周期中移动。即使每个人周期性地击中上半场，它们的周期也可能永远不会对齐，并且需要在组合周期内进行粗暴同步。 在这种情况下，算法会正确探索完整的最小公倍数范围，确保不会出现误报。
