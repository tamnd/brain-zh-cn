 ## 解决方案
 ## 问题理解

 我们有一行$N$完全相同的厕所，最初都是空的。 人们陆续到达，每个人都必须选择一个当前空着且两侧都没有占用的邻居的厕所。 换句话说，如果有人坐在这个位置$i$，那么两者$i-1$和$i+1$此时必须为空（或出界）。 

恰好之后$K$人们已经选择了，我们希望占用厕所的最终配置具有这样的属性：在相同的规则下，没有其他人可以选择任何位置。 我们必须要么构建这样的最终安排，要么确定这是不可能的。 

输出是一个长度的字符串$N$，其中“X”表示已占用的厕所，“-”表示空的厕所。 如果有可能达到一个确切的状态$K$有效的放置会导致系统完全阻塞，我们输出任何有效的最终配置。 否则我们输出一个“*”。 

限制条件$N \le 10^6$和$K \le N$强烈建议任何解决方案都必须是线性或近线性的。 重复扫描阵列并放置人员的二次模拟太慢，因为每次放置都可能会花费成本$O(N)$，导致$O(NK)$在最坏的情况下。 

一个微妙的问题是局部贪婪放置策略可能会失败。 例如，过早地将人员放置在边界附近可能会错误地减少未来的放置选项，从而产生无法完成的配置以阻止所有移动，即使存在有效的配置也是如此。 

另一个边缘情况出现时$K = 0$。 在这种情况下，我们需要一个已经完全阻塞的配置，没有有效的移动，但任何长度至少为 1 的空段总是允许移动，如果$N \ge 1$，所以唯一可能的时间是$N = 0$，这永远不会发生。 因此$K=0$除了琐碎的解释之外，隐含地导致不可能。 

在另一个极端，当$K = N$，我们被迫占据每个位置，但这显然违反了第一次放置后的邻接规则，因此完全占据对于$N > 1$。 

真正的困难是理解哪些配置没有有效的剩余移动。 该条件非常强：每个空单元格必须至少有一个被占用的邻居，这意味着空单元格只能出现在被占用单元格包围的孤立的单个间隙中。 

## 方法

 蛮力视角将模拟该过程。 我们维护当前数组并重复扫描任何有效位置$i$这样两个邻居都是空的，选择一个，将其标记为已占用，然后继续，直到不存在移动或我们已放置$K$人们。 这直接符合流程定义并且是正确的。 

然而，扫描整个阵列的每个放置成本$O(N)$，并这样做$K$次给$O(NK)$，这变成$10^{12}$最坏情况下的操作。 这远远超出了任何限制。 

关键的观察结果是最终状态才是重要的，而不是放置的顺序。 “不存在进一步移动”约束描述了一个结构条件：必须没有索引$i$这样$i$是空的，两个邻居都是空的。 这相当于说每个空段的长度最多为 2，并且任何长度为 3 或以上的段都必须包含一个占用的单元，该单元会阻止将来的插入。 

从这里，我们可以反过来推理。 我们不是模拟人们到达，而是直接构建最终模式。 每个被占用的单元都会“杀死”其两个相邻的空槽在将来不再可用。 因此，每个“X”有效地阻止了以其自身为中心的最大尺寸为 3 的窗口。 

因此，我们正在打包$K$“阻塞中心”变成一个长度-$N$线，使得在删除任何选定中心距离 1 内的所有位置后，没有剩余可用的插槽。 这成为一个覆盖问题：区间的并集$[i-1, i+1]$对于选定的指数，必须覆盖每个位置，除了可能孤立的、不允许任何中心的安全剩余位置。 

查看可行性的一个简洁方法是从左到右贪婪地工作。 我们尝试放置一个“X”，然后跳过下一个位置（因为它变得相邻），然后重复。 这会在距离 2 约束下产生最大独立集。 可实现的最大展示位置数量为$\lceil N/2 \rceil$。 如果$K$超过这个，任务是不可能完成的。 

然而，准确地实现$K$确保没有移动仍然需要稍微不同的视角：我们需要有效布局的最大配置，然后确保其饱和。 当不存在三个连续“-”的段时，配置正好饱和。 该条件意味着每个空游程的长度最多为 2。 

所以我们构造一个模式，避免“---”并准确包含$K$Xs。 我们可以根据剩余预算贪婪地构建“X-X”或“XX-”样式的块，确保我们永远不会创建免费的三重间隙。 

这简化为一条直线上的建设性堆积问题，可在线性时间内解决。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(NK) | O(N) | 太慢了|
 | 贪心建设| O(N) | O(N) | 已接受 |

 ## 算法演练

 我们从左到右构建最终的字符串，并保持仍需要多少个位置。 

1. 初始化答案为全“-”，并保留计数器`K_left = K`。 我们将在尊重邻接约束的同时填补职位，确保我们永远不会无意中创建未来的有效职位。 
2. 从左到右迭代位置。 在每个索引处$i$，检查是否允许我们放置“X”。 如果位置允许，我们可以$i$目前是空的，并且两个邻居都没有被之前的放置所强迫。 这确保了我们维持任何两个选定位置不能相邻的规则。 
3. 如果我们决定在$i$，我们设置`ans[i] = 'X'`， 减少`K_left`加 1，并跳过索引$i+1$。 跳过是必要的，因为放置在$i$使无效$i+1$由于邻接限制而成为有效候选者。 
4. 继续这种贪婪的放置，直到我们耗尽头寸或用完所需的放置。 如果在任何时候我们无法放置更多“X”但仍然有`K_left > 0`，施工是不可能的。 
5. 构建最大有效位置后，验证三个连续位置中没有一个段都是空的。 如果存在这样的段，仍然可以放置新的人员，因此该配置无效。 如果有效则输出。 

### 为什么它有效

 关键的不变量是我们永远不允许两个相邻的“X”位置，并且当我们仍然需要更多位置时，我们总是尽早放置一个“X”。 这确保了如果有效的配置$K$存在放置的情况下，贪婪过程不会提前跳过必要的位置，因为跳过只会减少未来的可用性，而不会增加灵活性。 所得到的配置在距离 2 约束下是最大的，并且最大意味着饱和：任何剩余的空位置必须至少有一个被占用的邻居，因此不可能进一步放置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    K, N = map(int, input().split())
    
    ans = ['-'] * N
    K_left = K
    
    i = 0
    while i < N and K_left > 0:
        # try place at i if possible
        # must ensure no adjacency violation
        if ans[i] == '-':
            ans[i] = 'X'
            K_left -= 1
            i += 2
        else:
            i += 1
    
    if K_left > 0:
        print("*")
        return
    
    # check no "free move" remains: no "---"
    for i in range(N - 2):
        if ans[i] == ans[i+1] == ans[i+2] == '-':
            print("*")
            return
    
    print("".join(ans))

if __name__ == "__main__":
    solve()
```该实现维护一个简单的贪婪指针。 一旦放置了“X”，我们立即跳过下一个位置，因为它会违反与我们的构造一致的任何进一步放置策略的邻接条件。 剩下的检查确保我们不会意外留下一个仍允许另一个有效插入的长空段。 

一个微妙的点是，贪婪步骤在放置“X”时不会显式检查邻居。 这是安全的，因为我们只会向前移动，而不会由于以下原因而放置在相邻索引处：`i += 2`跳。 最后的验证步骤是保证全局结构的正确性。

 ## 边缘情况

 一个关键的边缘情况是当$N = 1$。 唯一有效的输出是放置单个厕所，如果$K = 1$。 该算法处理这个问题是因为它放置在索引 0 处并立即满足`K_left = 0`，产生“X”。 

另一种情况是当$N = 2$。 不管怎样，放置一个人后，另一个位置总是有一个相邻的被占用的邻居，所以只有$K = 1$是可行的。 贪心循环放置在位置 0 并跳过 1，产生“X-”，该位置已经饱和。 

长空段也很关键。 例如，对于$N = 6, K = 2$，贪婪可能会产生“X-X---”，其中包含“---”并且会错误地表明存在未来的移动。 最终检查通过扫描任何三重自由段来捕获这一点，从而防止无效接受。 

这些案例证实，局部布局规则和全局饱和度检查对于避免微妙的无效构造都是必要的。
