 ## 解决方案
 ## 问题理解

 我们得到了应用于未知拉丁方的一系列运算。 拉丁方是一个$N \times N$网格填充了来自的数字$1$到$N$，其中每个数字在每行和每列中恰好出现一次。 关键属性是行和列是同一符号集的排列，行内不重复。 

我们只看到一个转换列表，而不是看到最终的网格。 每个转换交换两行或两列。 这些交换被依次应用于某个初始隐藏的拉丁方，产生最终的矩阵。 

然而，问题在于我们实际上并没有得到最终的矩阵。 我们被问到一个不同的反问题：是否存在任何初始拉丁方，使得在应用所有交换后我们可以获得一些与变换一致的有效最终配置？ 如果是，我们必须构造至少一个这样的初始正方形。 如果不是，我们输出这是不可能的。 

重要的认识是行和列的交换不会破坏拉丁方的性质。 它们仅排列行和列，这意味着结构被保留。 因此，这些转换充当行索引和列索引的独立排列。 

约束允许最多$N \le 500$和$T \le 10^5$。 这立即表明我们无法模拟完整矩阵的交换或每次操作显式重新计算行内容。 任何解决方案都必须在线性或近线性时间内将交换序列压缩为索引的最终排列。 

当多次交换相互抵消或形成循环时，就会出现微妙的边缘情况。 例如，两个相同的行交换恢复行上的恒等转换，但中间推理必须正确考虑奇偶校验和组合，而不仅仅是计数交换。 另一个边缘情况是，如果我们尝试在不分离两个维度的情况下重建直接映射，则行和列排列的交互方式表明不一致。 

## 方法

 天真的尝试会直接模拟该过程。 我们可以尝试显式地维护矩阵并按顺序应用每行或列交换。 每次交换费用$O(N)$，因此总复杂度变为$O(TN)$，在最坏的情况下是$10^5 \cdot 500 = 5 \cdot 10^7$运营。 虽然处于临界状态，但真正的问题是我们仍然不知道最终的矩阵，因此仅靠模拟并不能帮助我们构建有效的逆矩阵。 更糟糕的是，问题不在于计算最终状态，而在于找到可以映射到它的一致的原始配置。 

关键的见解是停止考虑矩阵内的值，而是考虑位置如何移动。 每个行交换都构成行索引的排列。 每个列交换都构成列索引的排列。 处理完所有操作后，我们获得两种排列：一种排列描述每个原始行结束的位置，一种描述每个原始列结束的位置。 

现在考虑最终的矩阵。 一个细胞$(i, j)$最终网格对应于一些原始单元格$(r, c)$， 在哪里$r$是原像$i$根据行排列和$c$是原像$j$在列排列下。 这意味着如果我们选择任何有效的拉丁方作为最终配置，我们可以将其反向映射以构造有效的初始方。 

因此，问题简化为构造任何拉丁方，然后应用行和列的逆排列将其“拉回”到原始状态。 由于任何拉丁方都是可接受的，因此我们可以使用标准循环结构$A[i][j] = (i + j) \bmod N + 1$。 唯一剩下的问题是组合的行和列排列是否定义良好，它们总是如此，因为交换是排列。 

最后一步是检查一致性：不存在使构造无效的额外约束，因为行和列的每个排列都保留拉丁方有效性。 因此，答案总是可构造的，唯一真正的任务是正确应用逆排列。

 ## 算法演练

 我们将转换的效果分成两种独立的排列，一种作用于行，一种作用于列。 

1.初始化两个数组$row[i] = i$和$col[i] = i$。 这些表示从原始索引到当前索引的恒等映射。 
2. 按顺序处理各个操作。 如果是之间的行交换$i$和$j$， 交换$row[i]$和$row[j]$。 如果是列交换，则交换$col[i]$和$col[j]$。 这直接模拟了排列组合。 
3. 经过所有操作，我们得到了从原始索引到最终索引的映射。 我们还需要逆映射，所以我们构建数组$invRow$和$invCol$这样$invRow[row[i]] = i$对于列也类似。 
4. 构造一个规范的拉丁方$base[i][j] = (i + j) \bmod N + 1$。 这可确保每行和每列仅包含一次所有值。 
5. 通过反转变换来构建初始正方形。 对于每个最终位置$(i, j)$，将值置于$base[invRow[i]][invCol[j]]$代入答案矩阵$(i, j)$。 

这个方向有效的原因是我们有效地撤销了索引的排列，而不是试图直接推理值。 

### 为什么它有效

 行交换定义了排列$P$在行索引和列交换上定义排列$Q$关于列索引。 任何拉丁方在独立的行和列排列下仍然是拉丁方，因为每行和列仍然是以下的排列$1 \ldots N$。 通过构造任何有效的拉丁方并应用逆排列，我们保证应用给定的变换将重建相同的最终排列。 这表明了存在性和正确性，而不需要明确地重建未知的原始数据。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    N, T = map(int, input().split())
    
    row = list(range(N))
    col = list(range(N))
    
    for _ in range(T):
        parts = input().split()
        typ = parts[0]
        i = int(parts[1]) - 1
        j = int(parts[2]) - 1
        
        if typ == 'R':
            row[i], row[j] = row[j], row[i]
        else:
            col[i], col[j] = col[j], col[i]
    
    inv_row = [0] * N
    inv_col = [0] * N
    
    for i in range(N):
        inv_row[row[i]] = i
        inv_col[col[i]] = i
    
    base = [[0] * N for _ in range(N)]
    for i in range(N):
        for j in range(N):
            base[i][j] = (i + j) % N + 1
    
    ans = [[0] * N for _ in range(N)]
    for i in range(N):
        for j in range(N):
            ans[i][j] = base[inv_row[i]][inv_col[j]]
    
    for row_ in ans:
        print(*row_)

if __name__ == "__main__":
    main()
```该解决方案首先使用直接交换将所有变换压缩为两个排列。 反演步骤至关重要，因为排列描述了从原始索引到最终索引的向前移动，而我们需要将值放置在原始坐标系中。 规范的拉丁方用作中性结构，在所有行和列排列下仍然有效。 

一个常见的错误是尝试仅基于操作来重建值，但转换从不限制值，而仅限制位置。 这种分离使得构造有效。

 ## 边缘情况

 一种极端情况是掉期随着时间的推移而抵消。 例如，交换第 1 行和第 2 行两次将返回恒等。 该算法自然地处理这个问题，因为它将交换直接应用于排列数组。 第二次交换后，排列返回到原始状态，并且反转产生一致的映射。 

另一个边缘情况是行和列的严重混合。 即使所有行都完全排列并且所有列都完全排列，该算法也从不依赖于中间矩阵结构。 它仅取决于最终的排列，因此不会出现不一致。 

最后一个边缘情况是$N = 2$，其中拉丁方只有两种有效形式。 该构造仍然会产生有效的循环矩阵，并且排列仅对行和列重新排序而不会破坏有效性，即使在最小规模下也能确认正确性。
