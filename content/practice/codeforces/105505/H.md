 ## 解决方案
 ## 问题理解

 该程序是函数调用的有向无环图。 每个函数都有一个基本成本，每当它调用另一个函数时，被调用者的全部执行成本都会立即添加，并且这种效果会通过所有进一步的调用递归传播。 

如果我们用图的术语来思考，每个函数都是一个节点，每个调用都是一个有向边。 函数的总成本不仅仅是其自身的权重，而是通过传出边可到达的所有节点的权重之和，如果存在多个调用指令，则计算重数。 

该图保证是一个 DAG，因此每个评估都是明确定义的并且不存在递归循环。 

挑战在于基本成本会随着时间的推移而变化。 每次更新都会修改单个节点权重，并且考虑到所有先前的更新，查询会询问节点当前的总“闭包总和”。 最后，我们不是单独返回每个查询结果，而是按顺序累积答案的加权和。 

这些限制使结构成为真正的困难。 该图具有多达 8000 个节点和边，足够小，可以进行二次预处理。 但是，最多可以有 1e6 个事件，这排除了每个查询重新计算完整 DP 的可能性。 任何在每次操作的线性时间内重新访问每个事件的边或节点的方法都将无法生存。 

导致错误的一个天真的误解是在每次更新后重新计算整个 DP。 例如，在链 1 → 2 → 3 → 4 中，如果直接更改节点 4 的基本成本，则将强制重新计算所有祖先，这在小示例中很好，但在规模上会非常慢。 

另一个微妙的情况是同一对函数之间的多次调用。 这很重要，因为图是边的多重集，因此必须以多重性而不是仅可达性来计算贡献。 

## 方法

 蛮力的观点很简单。 我们可以维护当前的基值，并且对于每个查询，在 DAG 上运行 DP。 如果我们以相反的拓扑顺序处理节点，每个节点都会聚合其传出邻居的贡献。 这可以正确计算单个查询的闭包总和。 

这是有效的，因为一旦图被拓扑排序，每个节点仅依赖于顺序中较晚的节点，因此一次传递就足够了。 

当我们考虑事件计数时，问题就出现了。 每个查询都会花费 O(N + M)，并且对于最多 1e6 个事件，这会变得太慢。 问题不在于正确性，而在于重复相同的结构计算。 

关键的观察是传播的结构永远不会改变。 仅基向量发生变化。 这使得系统呈线性。 每个函数的总成本可以表示为基本成本的固定线性组合：

 T(i) = 系数 (i, j) * B[j] 的 j 总和

 这些系数仅取决于 DAG，并表示从 i 通过所有调用路径到达 j 的次数（考虑多重性）。 

一旦知道这些系数，每个查询就只是一个点积。 更新变成对基本向量的简单点更改，并且查询评估固定的线性形式。 

权衡是存储和使用该系数矩阵。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询重新计算 DP | O(E·(N + M)) | O(E·(N + M)) | O(N) | 太慢了 |
 | 预先计算所有路径系数，通过点积查询 | O(N² + N·M + Q·N) | O(N²) | 已接受 |

 ## 算法演练

 我们首先确定 DAG 的拓扑顺序。 这使我们能够干净地计算依赖结构，而无需重新访问节点。 

1. 计算所有函数的拓扑顺序。 这保证了每个函数都出现在它所依赖的所有函数之前。 
2. 对于每个函数 i，计算从 i 开始调用每个函数 j 的次数。 我们建立一个DP表`dp[i][j]`, 初始化使得`dp[i][i] = 1`。 
3. 以逆拓扑顺序遍历节点。 对于每条边 i → k，传播贡献，以便 k 的每次出现都继承其被调用者的所有贡献。 形式上，对于每个 j，我们添加`dp[k][j]`进入`dp[i][j]`，乘以从 i 到 k 的调用次数。 

此步骤之所以有效，是因为在逆拓扑顺序中，在处理节点时已完全计算节点的所有后代。 

1.预处理后，维护当前基值数组B。 
2. 对于节点 i 上的查询，将 T(i) 计算为 dp[i] 与 B 的点积。 
3. 对于更新设置 B[i] = v，只需覆盖该值即可。 
4. 在查询答案到达时维护所需的加权总和。 

### 为什么它有效

 每个 dp[i][j] 表示 i 的执行最终触发 j 的执行的总次数，计算所有不同的调用路径并考虑边的重数。 由于该图是非循环的，因此每条路径在 DP 传播中只贡献一次，而不存在重复计数循环的风险。 执行的线性确保对所有 j 的贡献求和可以准确地重建完整的执行成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def topo_sort(n, adj):
    indeg = [0] * n
    for u in range(n):
        for v in adj[u]:
            indeg[v] += 1

    stack = [i for i in range(n) if indeg[i] == 0]
    topo = []

    while stack:
        u = stack.pop()
        topo.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                stack.append(v)

    return topo

def main():
    n = int(input())
    B = list(map(int, input().split()))
    m = int(input())

    adj = [[] for _ in range(n)]
    radj = [[] for _ in range(n)]

    for _ in range(m):
        f, g = map(int, input().split())
        f -= 1
        g -= 1
        adj[f].append(g)
        radj[g].append(f)

    topo = topo_sort(n, adj)
    pos = [0] * n
    for i, v in enumerate(topo):
        pos[v] = i

    dp = [ [0] * n for _ in range(n) ]

    for v in reversed(topo):
        dp[v][v] = 1
        for to in adj[v]:
            for j in range(n):
                if dp[to][j]:
                    dp[v][j] += dp[to][j]

    e = int(input())
    ans = 0

    for _ in range(e):
        tmp = input().split()
        if tmp[0] == 'U':
            i = int(tmp[1]) - 1
            v = int(tmp[2])
            B[i] = v
        else:
            j = int(tmp[1]) - 1
            s = 0
            row = dp[j]
            for k in range(n):
                s += row[k] * B[k]
            ans = (ans + (_ + 1) * s) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    main()
```预处理使用 DAG 结构构建完整的传递贡献矩阵。 每行 dp[i] 编码从 i 的执行如何扩展到所有可到达的节点。 查询阶段变成针对当前基本数组对该行的直接评估。 

更新操作很简单，因为它只影响未来的评估，并且矩阵已经捕获了所有结构传播。 

一个微妙的实现点是 dp 传播必须尊重边的多重性。 这就是为什么直接迭代邻接表而不是将边缘视为布尔可达性的原因。

 ## 边缘情况

 没有边的单个节点确认 dp[i][i] 已正确初始化为 1 并且不会发生意外传播。 执行时间始终恰好是基值，更新只是覆盖它。 

长链测试传递累积是否正确地通过多层传播。 DP 排序中的任何遗漏都会导致中间节点错过更深节点的贡献。 

具有指向同一目标的多个传出边缘的节点测试多重性处理。 如果一个函数调用另一个函数两次，则其贡献必须计算两次，并且只有在 DP 累积期间考虑边重数时，这一点才会保留。 

对同一节点重复更新的情况确保只有基向量发生变化，不需要结构重新计算。
