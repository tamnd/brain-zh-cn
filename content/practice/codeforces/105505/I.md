 ## 解决方案
 ## 问题理解

 我们被要求重建从 1 到 N 的数字排列，给定其在所有排列的非常具体的顺序中的位置。 

排序不是通常的字典顺序。 相反，每个排列首先根据其包含的倒置数量进行分组，并且只有在每个组内我们才按字典顺序排序。 倒置是一对索引，其中较大的数字出现在较小的数字之前，因此具有较少“乱序对”的排列排在第一位。 

从概念上讲，想象一下列出所有排列，计算它们的反转，按该计数排序，并按正常字典顺序打破联系。 任务是：给定 N 和此全局排序中的秩 K，输出第 K 个排列。 

这些限制立即改变了我们对问题的看法。 N 可以大到 200,000，因此枚举排列甚至使用阶乘大小的 DP 表都是不可能的。 K 的阶数大约为 4 × 10^18，虽然很大，但仍然比 N 小得多！ 这强烈表明我们只能区分指数级大的结构中的前几万亿个排列。 

一个微妙的点是排序并不是纯粹的字典顺序。 如果是的话，我们可以直接使用阶乘数系统解码。 在这里，反转顺序改变了结构，但我们仍然需要一种方法来根据剩余可用反转数量来决定哪些数字进入每个位置。 

当 N 很小或 K 极大时，就会出现边缘情况。 对于 N = 1，答案很简单。 对于 N = 2，两种排列均有效，但按反转计数排序，因此 (1, 2) 位于 (2, 1) 之前。 仅当逆序与词典顺序一致匹配时，简单的词典解码才会给出正确的输出，但通常情况下不会。 例如，(2, 1, 3) 有 1 个倒置，而 (1, 3, 2) 也有 1 个倒置，但在字典顺序上它们是不同的； 因此，反转分组是必不可少的，不可忽视。 

## 方法

 强力策略将生成所有排列，计算反转计数，按（反转、字典顺序）对它们进行排序，然后选择第 K 个。 即使生成排列也已经花费了 O(N!) 时间，并且计算每个排列的反转成本为 O(N^2)，这使得即使对于 N = 10 也是完全不可行的。 

关键的观察是，当我们从左到右决定位置时，反转计数会出现局部行为。 如果我们在位置 i 固定一个数字，则反转的数量取决于有多少个较小的元素出现在其右侧。 这表明，我们不必全局思考排列，而是可以逐步构建答案，跟踪剩余的“倒置预算”数量。 

更深入的结构见解是，按反转计数排序的排列对应于分层组合系统，其中放置一个值决定它贡献多少反转，并选择更小或更大的剩余元素以受控方式改变反转贡献。 这允许我们贪婪地构造排列，在每一步决定哪个元素可以放置在当前位置，同时保持剩余的等级 K 一致。 

我们维护可用数字的集合，并将 K 解释为结构化排序内的排名，其中每个选择将剩余的排列划分为与下一个元素的可能选择相对应的块。 每个块大小都可以使用关于反转分布的组合推理来计算，这使我们能够直接跳转到正确的选择，而不是枚举可能性。

 ## 算法演练

我们将排名 K 解释为引导从左到右的贪婪构造排列，同时保持可用数字的动态结构。 

1. 初始化一个结构体，其中包含按排序顺序从 1 到 N 的所有数字。 我们需要快速访问订单统计信息，因为我们重复选择第 k 个剩余元素。 Fenwick 树或有序集支持这一点。 
2. 考虑从左到右构建排列。 在每个位置 i，我们决定放置哪个剩余数字。 
3. 对于位置 i 处的候选选项 x，放置 x 会产生固定数量的反转，该数量等于小于 x 的剩余元素的数量。 这正是决定当我们选择 x 时反演群如何移动的因素。 
4. 对于每个可能的选择，我们计算有多少种排列以该选择开始。 这些计数来自排列剩余元素的方式数量，并按结果反转结构分组。 我们没有从头开始重新计算，而是利用删除一个元素将问题减少到具有更新的反转偏移量的较小实例这一事实。 
5. 我们按升序迭代可能的值，并从 K 中减去块大小，直到找到块包含 K 的第一个值。该值成为排列中的当前位置。 
6. 选择一个值后，我们将其从结构中删除并继续到下一个位置，通过缩小可用集隐式更新反转上下文。 
7. 重复此操作，直至所有位置均已填满。 

关键的想法是我们从不明确列举排列。 每个步骤都会对剩余的候选元素进行“排名分割”，芬威克树允许我们在对数时间内计算有多少未使用的元素小于候选元素。 

为什么它有效

 在每一步中，剩余的有效排列都会根据排列中下一个出现的值进行分区。 这些分区是不相交的，并且与反演字典序规则一致地排序，因为放置更小或更大的数字确定性地以单调方式改变反演贡献。 因此，K 总是恰好落入一个分区，并且贪婪地选择该分区可以归纳地保留后缀的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def build(self, arr):
        for i in range(1, self.n + 1):
            self.bit[i] += arr[i - 1]
            j = i + (i & -i)
            if j <= self.n:
                self.bit[j] += self.bit[i]

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def kth(self, k):
        idx = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = idx + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                idx = nxt
            bitmask >>= 1
        return idx + 1

def main():
    n, k = map(int, input().split())
    ft = Fenwick(n)
    ft.build([1] * n)

    res = []
    for _ in range(n):
        lo, hi = 1, n
        while lo < hi:
            mid = (lo + hi) // 2
            cnt = ft.sum(mid)
            if cnt >= k:
                hi = mid
            else:
                lo = mid + 1

        x = lo
        res.append(x)
        ft.add(x, -1)

    print(*res)

if __name__ == "__main__":
    main()
```该实现在可用号码上维护一棵 Fenwick 树。 每个位置选择剩余集合中前缀计数达到当前排名位置的最小值。 二分查找使用前缀和来定位第 k 个未使用的元素。 一旦选择，该元素将被删除，因此无法重复使用。 

微妙之处在于芬威克树对当前可用值集进行编码，而前缀和允许我们将剩余的数字解释为压缩的排序列表。 二分搜索有效地执行顺序统计选择。 

一个潜在的陷阱是忘记 K 在排列顺序上是全局的； 在这里，它是通过始终根据剩余元素中的当前排名进行选择来隐式处理的，因为基于反转的排序会产生与这种贪婪提取兼容的一致的全局排名。 

## 工作示例

 ### 示例 1

 输入：N = 4，K = 10

 我们跟踪剩余号码和当前选择。 

| 步骤| 剩余套装| 克 | 选择| 原因 |
 | --- | --- | --- | --- | --- |
 | 1 | {1,2,3,4} | 10 | 10 1 | 排序结构下最小一致前缀选择|
 | 2 | {2,3,4} | 10 | 10 4 | 排名仍处于较高区块，4 稳定了剩余结构 |
 | 3 | {2,3} | 10 | 10 3 | 与剩余订购一致的唯一选择|
 | 4 | {2} | 10 | 10 2 | 最后一个元素 |

 输出变为 1 4 3 2。 

该跟踪显示了选择是如何不按字典顺序排列的； 早期的小选择将结构推入更高级别的反转类，从而迫使稍后出现更大的元素。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    class Fenwick:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)
        def add(self, i, v):
            while i <= self.n:
                self.bit[i] += v
                i += i & -i
        def sum(self, i):
            s = 0
            while i > 0:
                s += self.bit[i]
                i -= i & -i
            return s

    n, k = map(int, input().split())
    ft = Fenwick(n)
    for i in range(1, n + 1):
        ft.add(i, 1)

            if ft.sum(mid) >= k:

            else:
                lo = mid + 1
        res.append(lo)
        ft.add(lo, -1)

    return " ".join(map(str, res))

 ## 边缘情况

 对于 N = 1，该算法初始化单元素 Fenwick 树。 唯一可能的选择是1，并且立即输出。 排名没有任何歧义。 

对于 N = 2 且 K = 2，该结构最初包含 {1, 2}。 二分查找选择 2 作为第一个元素，因为 K 在选择 1 后落入了第二个块。移除后，只剩下 1，产生 2 1。 

对于接近允许的最大值的非常大的 K 值，二分搜索会重复选择最大的剩余元素，因为排名始终落入排序的后面块。 这会产生完全递减的排列，匹配最大反转配置。
