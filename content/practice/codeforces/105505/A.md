 ## 解决方案
 ## 问题理解

 我们得到一个由两步过程生成的大写字符串。 首先，有人有一个原始字符串`t`。 然后他们通过取所有不同的字母创建了第二个字符串`t`，按字母顺序对它们进行排序，并将每个字母写一次。 最后，他们没有用这个派生字符串替换原始文件，而是将其附加到原始文件中。 

所以输入字符串`S`实际上是`S = t + g(t)`， 在哪里`g(t)`是出现在的唯一字符的排序字符串`t`。 

任务不是重建`t`本身，仅确定其长度。 

约束允许字符串长度最大为 2000。这足够小，任何二次或接近二次的解决方案都可以轻松通过，但它也暗示存在隐藏的结构属性，因为转换涉及排序和重复数据删除，这通常将信息减少到较小的固定字母大小。 

一个关键的观察是`g(t)`仅包含不同的大写字母。 由于只有 26 个大写字母，因此附加后缀的长度最多为 26。这立即排除了任何尝试在所有 2000 个索引中任意分割位置作为主要策略的方法，因为我们可以将边界定位到靠近末尾的非常小的区域。 

一个天真的错误是假设分割点在字符串中的任何地方都是未知的。 例如，给定`S = "ICPCCIP"`，人们可能会尝试分成多个位置并验证每个位置，这可行但没有必要。 

另一个微妙的边缘情况是当`t`它本身已经包含按排序顺序排列的所有不同字母。 例如，如果`t = "ABC"`， 然后`g(t) = "ABC"`，所以最终的字符串变成`"ABCABC"`。 如果不仔细推理，重复会使分割点看起来不明确。 

真正的挑战是认识到后缀完全由前缀中的字符集决定，并且其长度是有限的。 

## 方法

 直接暴力方法尝试每一个可能的分裂点`i`从`1`到`n-1`。 对于每个分割，我们对待`S[:i]`作为候选人`t`，计算字符集，对它们进行排序，然后与`S[i:]`。 如果它们匹配，我们返回`i`。 

这是正确的，因为它直接强制执行构造的定义。 然而，对于每个分割，我们可能会重建一个集合并排序最多 26 个字符，这很便宜，但我们这样做了`O(n)`次，导致大约`O(n^2)`最坏情况下的字符处理。 和`n = 2000`，这仍然是边界罚款，但没有必要。 

关键的见解是第二部分`g(t)`正是经过排序的字符集`t`，因此它的长度是中不同字符的数量`t`。 该数字最多为 26。这意味着分割点必须在字符串的最后 26 个字符内。 

因此我们可以尝试所有可能的后缀长度`k`从`1`到`26`， 解释`S[n-k:]`作为候选人`g(t)`，并检查是否匹配前缀排序后的唯一字符`S[:n-k]`。 其中之一将完全匹​​配。 

这将问题从扫描最多 2000 个分割点减少到检查最多 26 个候选点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分割检查 | O(n²) | O(1) 额外 | 已接受但没有必要 |
 | 尝试后缀长度≤26 | O(26·n) | O(26·n) | O(1) 额外 | 已接受 |

 ## 算法演练

 我们利用了这样一个事实：附加部分是原始字符串的排序、去重复版本，因此它的大小完全由前缀中不同字符的数量决定。 

1. 让`n`的长度是`S`。 我们认为后缀对应于`k`对某些人来说有独特的性格`k`之间`1`和`26`。 这是因为只有 26 个大写字母，因此去重后的字符串不能超过此长度。 
2. 对于每位候选人`k`，我们取最后一个`k`的字符`S`作为一个潜在的`g(t)`。 这是假设的后缀。 
3.我们计算前缀`S[:n-k]`，将其解释为`t`，并提取其字符集。 对该集合进行排序会产生预期的形式`g(t)`。 
4. 我们将计算出的排序后的唯一字符串与后缀进行比较。 如果它们完全匹配，那么`n-k`是原始字符串的正确长度。 
5.我们回来了`n-k`一旦找到匹配就立即进行。 

### 为什么它有效

 该结构保证后缀由前缀中的字符集唯一确定。 因此，一旦我们修复了候选分割点，后缀就被迫等于该前缀的排序后的唯一字符。 由于真实后缀也必须满足这个条件，因此它必须出现在`k`。 26 的上限确保我们不会错过正确的分割，并且无效的分割不会意外地满足相等条件，因为字符集或顺序中的任何不匹配都会破坏构造。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    for k in range(1, 27):
        if k > n:
            break
        suffix = s[n - k:]
        prefix = s[:n - k]

        if len(set(prefix)) != k:
            continue

        if ''.join(sorted(set(prefix))) == suffix:
            print(n - k)
            return

solve()
```该实现直接对可能的后缀长度上的有界搜索进行编码。 唯一的微妙之处是确保我们永远不会尝试使用比字符串本身更长的后缀，并将后缀与前缀的规范形式进行比较。 

一个常见的错误是忘记后缀已排序并已消除重复，因此将其与未排序的集合表示进行比较将会失败。 另一个是迭代分割位置直到`n`，与使用字母大小限制相比，这是不必要的且结构性较差。

 ## 边缘情况

 一种边缘情况是当所有字符都在`t`是相同的。 例如，`S = "AA"`。 唯一有效的解释是`t = "A"`和`g(t) = "A"`，所以答案是`1`。 算法检查`k = 1`，计算前缀`"A"`，其独特的排序形式`"A"`，并匹配后缀`"A"`。 

另一个边缘情况是当`t`包含全部 26 个字母。 在这种情况下，后缀长度恰好是 26。该算法仍然有效，因为它显式测试 26 以内的所有值并将匹配完整的字母后缀。 

第三种情况是前缀包含分散在字符串中的重复字母，例如`"ABABAB"`。 重复数据删除步骤确保计算出的后缀保持稳定`"AB"`，因此重复字母的任何排列都不会影响正确性。
