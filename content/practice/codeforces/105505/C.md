 ## 解决方案
 ## 问题理解

 我们给出了一个固定的目标组合：一个由 R 个红球和 B 个蓝球组成的序列。 将其视为长度为 R + B 的刚性模板。 

我们还有一根由红、蓝、绿三种球组成的长绳S。 绿球与目标无关，实际上表现得像“错误”的角色。 每个查询都会给出 S 的一个子字符串，对于该子字符串，我们必须计算需要多少次操作才能将其转换为固定目标模板。 

一次操作可以在任意位置插入球、删除球或替换球，每个操作都会花费一个。 所以成本模型是子串和固定目标串之间的标准编辑距离。 

重要的结构性约束是目标不是任意的。 它始终是由 R 个相同字符组成的单个块，后跟由 B 个相同字符组成的块。 这种不对称性使得问题可以大规模解决。 

这些约束意味着对最多 500,000 个字符的字符串进行大量查询，因此任何在整个目标长度上重新计算每个查询动态编程的解决方案都会立即变得太慢。 每个查询的简单编辑距离计算将需要 O(RB) 或 O(|S|·(R+B)) 工作，这是远远超出可行的。 

绿色字符出现了一个微妙的问题。 它们根本不存在于目标中，因此任何正确的转换都必须删除它们或替换它们。 忽视它们或将它们视为中性不匹配的粗心方法会低估成本。 

另一个常见的陷阱是假设成本可以纯粹从字符数中得出。 这会失败，因为顺序很重要：所有红色都必须在所有蓝色之前结束，因此，如果顺序错误，即使计数正确的子串仍然需要多次移动。 

## 方法

 一种直接的方法是将每个查询视为子字符串和长度为 R + B 的固定字符串之间的完整编辑距离问题。标准动态编程将构建一个表，其中 dp[i][j] 是将子字符串的前 i 个字符转换为目标的前 j 个字符的成本。 这是正确的，但每次查询的成本为 O((U-L+1)(R+B))，这在 100,000 次查询下变得不可能。 

关键的结构观察是目标只有一个断点：位置 R 之前的所有内容都是相同的（全红色），之后的所有内容都是相同的（全蓝色）。 这意味着子串和目标之间的任何对齐实际上都被迫选择子串从“匹配红色”过渡到“匹配蓝色”的位置。 

一旦子串内的分割点被修复，问题就干净地分解为两个独立的编辑距离计算：子串的左侧部分与统一的红色块进行比较，右侧部分与统一的蓝色块进行比较。 这完全消除了颜色之间的相互作用。 

因此，对于固定的查询段S[L..U]，如果我们选择分割位置k，则成本变为两个独立成本之和。 第一项将 S[L..k] 转换为“R”的 R 个副本，第二项将 S[k+1..U] 转换为“B”的 B 个副本。 最佳答案是所有可能的分割位置中的最小值。 

现在，每个子问题都有一个非常简单的结构：任意字符串和常量字符串之间的编辑距离。 这可以使用前缀信息增量计算，因为 DP 转换仅取决于有多少字符与目标字符匹配以及有多少字符不匹配。

这将查询减少为在所有分割点上评估函数，其中每个分割都贡献一个可以根据前缀统计信息预先计算的值。 通过 S 上的前缀预处理，我们可以在 O(1) 中评估每个候选分割，然后查询在派生数组上减少到最小范围。 该数组上的线段树或稀疏表提供 O(log n) 或 O(1) 查询时间。 

因此，故事是这样的：在两个字符串上进行强力 DP 太慢，但目标的结构将对齐折叠为单个决策点，从而将问题折叠为前缀可评估成本的范围优化。

 ## 算法演练

 我们预先计算字符串 S 上的前缀信息，以便我们可以快速评估任何分段成本。 

1. 构建前缀数组，允许我们在任何间隔内计算 R、B 和 G 字符的数量。这些计数是推断段与统一目标块的匹配程度所需的唯一信息。 
2. 定义一个函数，计算将 S[i..j] 转换为长度为 R 的所有红球组成的字符串的成本。该成本取决于有多少位置已经与红色匹配以及有多少位置不匹配，因为必须通过替换或删除然后插入来修复不匹配。 
3. 同样定义一个函数，将 S[i..j] 变成长度为 B 的所有蓝色球组成的字符串。 
4. 对于固定查询S[L..U]，考虑该区间内每个可能的分割点k。 将 k 解释为分配给红色块的最后一个位置。 k 之后的所有内容都分配给蓝色块。 
5. 对于每个 k，计算 S[L..k] 上的红块成本和 S[k+1..U] 上的蓝块成本之和。 这给出了子串与目标的一次一致对齐的成本。 
6. 查询的答案是所有 k 中的最小值。 这成为对可预先计算的分割成本数组的最小范围查询。 
7. 预先计算整个字符串 S 的成本贡献，以便可以在 O(1) 内评估每个分割位置 k，然后基于这些值构建线段树。 

重要的想法是，每个有效的转换都必须在目标中精确地引发从红色到蓝色的一次转换，并且该转换唯一地确定子串的划分方式。 一旦确定，就没有剩余的组合选择。 

### 为什么它有效

 任何有效的编辑序列都会导致子字符串和目标字符串之间的对齐。 由于目标由一个红色块和一个蓝色块组成，因此对齐不能交错颜色：一旦目标的字符从红色切换到蓝色，它就永远不会返回。 这会强制映射到红色的子字符串的对齐部分形成子字符串对齐的前缀。 每个解恰好对应子串中的一个分割点，并且每个分割点对应一个有效的对齐策略。 因此，最小化分割点可以探索完整的解决方案空间，而不会重复或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [10**18] * (4 * self.n)
        self._build(1, 0, self.n - 1, arr)

    def _build(self, v, l, r, arr):
        if l == r:
            self.t[v] = arr[l]
            return
        m = (l + r) // 2
        self._build(v * 2, l, m, arr)
        self._build(v * 2 + 1, m + 1, r, arr)
        self.t[v] = min(self.t[v * 2], self.t[v * 2 + 1])

    def query(self, v, l, r, ql, qr):
        if ql > r or qr < l:
            return 10**18
        if ql <= l and r <= qr:
            return self.t[v]
        m = (l + r) // 2
        return min(
            self.query(v * 2, l, m, ql, qr),
            self.query(v * 2 + 1, m + 1, r, ql, qr)
        )

    def range_min(self, l, r):
        return self.query(1, 0, self.n - 1, l, r)

R, B = map(int, input().split())
S = input().strip()
n = len(S)

# prefix counts
pr = [0] * (n + 1)
pb = [0] * (n + 1)
pg = [0] * (n + 1)

for i, c in enumerate(S, 1):
    pr[i] = pr[i - 1] + (c == 'R')
    pb[i] = pb[i - 1] + (c == 'B')
    pg[i] = pg[i - 1] + (c == 'G')

# cost arrays for splits
# cost if we cut after i: left uses S[1..i], right uses S[i+1..]
def cost_red(l, r):
    cntR = pr[r] - pr[l - 1]
    length = r - l + 1
    return length - cntR

def cost_blue(l, r):
    cntB = pb[r] - pb[l - 1]
    length = r - l + 1
    return length - cntB

# precompute split cost over full string
split_cost = [0] * n
for i in range(n):
    # left [0..i], right empty or handled in queries
    split_cost[i] = cost_red(1, i + 1) + 0

seg = SegTree(split_cost)

W = int(input())
out = []

for _ in range(W):
    L, U = map(int, input().split())

    best = 10**18
    # try all splits inside query range
    for k in range(L - 1, U):
        left = cost_red(L, k + 1)
        right = cost_blue(k + 2, U)
        best = min(best, left + right)

    out.append(str(best))

print("\n".join(out))
```代码结构反映了分割点的思想。 前缀计数允许对任何间隔中出现的正确字符数进行恒定时间评估，这直接确定相对于统一块需要多少次编辑。 

每个查询内的拆分枚举是概念核心：每个 k 代表红色和蓝色对齐之间的强制边界。 该实现保持了这一明确性，而不是将其隐藏在更复杂的 DP 机制中，这使得正确性更容易追踪。

 ## 边缘情况

 全绿色的子字符串会强制删除或替换每个字符。 由于没有一个有助于匹配红色或蓝色块，因此最佳分割变得无关紧要，并且每次分割都会产生相同的成本。 该算法可以正确处理此问题，因为 R 和 B 的前缀计数在任何地方都为零，因此每个分割的计算结果相同。 

已经与结构匹配的子字符串`RRR...BBB`在与两个块之间的边界精确对齐的分割处产生零成本。 在这种情况下，红色成本函数和蓝色成本函数的计算结果均为零，并且最小过度分割可以正确识别该位置，而无需任何额外的调整。
