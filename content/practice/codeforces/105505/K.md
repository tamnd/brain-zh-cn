 ## 解决方案
 ## 问题理解

 我们给定一个二进制字符串和一个阈值$K$。 如果该字符串包含一系列内容，则该字符串被视为“坏”$K$或更多相同的连续字符，意味着像这样的块$0000$什么时候$K = 4$， 或者$111$什么时候$K = 3$。 “kool”字符串只是一个二进制字符串，其中每个最大相等字符块的长度严格小于$K$。 

我们可以翻转单个字符，将 0 变成 1 或 1 变成 0，并且我们希望以最少的翻转次数将原始字符串转换为任何有效的 kool 字符串。 我们还必须输出一个这样的结果字符串。 

关键的困难在于翻转角色并不是孤立地在局部发生作用。 稍微改变一下就可以将长的运行分割成更小的运行，或者在未来的翻转后合并相邻的运行，因此问题在于在付出最小成本的同时全局地将长的片段分解成允许的片段。 

输入尺寸可以达到$10^5$，这会立即排除任何尝试考虑所有可能修改的字符串或针对每个决策运行所有子段的解决方案。 任何二次方的事情，例如在每次假设翻转后重新计算有效性，都太慢了。 我们需要一个线性或近线性的贪心构造。 

当长跑恰好出现在边界处或翻转决策后重叠时，就会出现微妙的边缘情况。 例如，如果$K = 3$字符串是$00000$，一种简单的方法，即独立翻转每三个字符可能会产生类似的结果$01010$，这是有效的，但不一定是最佳的，具体取决于分组策略。 正确的解决方案必须确保翻转在每次最大运行中得到协调，而不是孤立地逐个位置决定。 

另一个边缘情况是当$K = 2$。 在这种情况下，两个相等的字符不能相邻，因此目标字符串必须严格交替。 这种特殊情况可能会误导天真的基于运行的思维，因为每对相等的邻居都会立即无效。 

## 方法

 暴力方法会尝试所有可能的结果字符串并选择最好的一个。 由于每个位置可以是 0 或 1，所以有$2^n$候选人，并检查每个测试的有效性$O(n)$，导致指数$O(n2^n)$的解决方案，即使对于小规模的解决方案也是不可行的$n$。 

更结构化的蛮力通过观察最终字符串完全通过选择如何将原始字符串分割成长度最多的块来完全确定，从而改善了这一点$K-1$，然后决定每个块的特征。 然而，即便如此，枚举所有分段仍然呈指数增长，因为每个边界选择都会与下一个边界选择相互作用。 

关键的见解是停止考虑任意翻转，而是考虑在原始字符串中每个最大相同字符的本地修复违规行为。 假设我们看一个片段$000000$。 任何有效的最终字符串都必须将其分成最多大小的块$K-1$。 以最少的翻转次数做到这一点的唯一方法是决定哪些位置保持相同的字符以及翻转哪些位置以创建中断。 至关重要的是，在单次运行中，最佳策略独立于其他运行，因为翻转无法在不支付额外成本的情况下合并不同原始值的运行，而这无助于减少其他地方的违规行为。 

这减少了单独处理每个最大运行的问题。 对于每个长度$L$，我们希望将其转换为超过两个字符的字符串，这样相同字符的片段不会超过$K-1$，成本是从原始运行字符改变的位置数。 由于运行是均匀的，因此决策简化为选择在运行内翻转的位置，以便没有段超过$K-1$，同时最大限度地减少翻转。 

这成为一个经典的贪婪分组问题：我们遍历每次运行并强制我们不允许超过$K-1$连续相同的最终字符，仅在必要时选择翻转。

 ## 算法演练

 我们从左到右处理字符串，但关键结构是我们对相等字符的最大运行进行操作。 

1. 将字符串拆分为所有字符都相同的最大分段。 每个段都可以独立处理，因为任何改变其特征的翻转仅影响局部邻接约束，而不影响其他运行的内部结构。 
2. 对于每个段，我们决定如何将其转换为从不包含的有效输出$K$连续的相等字符。 由于原始片段是统一的，我们将该任务解释为决定一种翻转模式，该模式最多将长距离分割成大小块$K-1$。 
3. 遍历该段并维护一个计数器，记录当前输出运行中有多少字符与原始段字符匹配。 如果计数器达到$K$，我们被迫将当前位置翻转到相反的位，因为否则我们将违反约束。 此重置可确保我们永远不会在构造的字符串中构建无效的运行。 
4. 当我们翻转一个字符时，我们还会重置当前输出运行的计数器，因为我们现在正在构建相反字符的运行。 这很重要，因为有效性是按字符值定义的，而不是按原始段定义的。 
5. 当我们继续进行时，将每个构造的字符附加到答案中。 翻转的总数就是构造的字符与原始字符串不同的位置数。 

这种贪婪的执行确保我们只在绝对必要时进行翻转，这意味着我们永远不会引入不必要的更改。 

### 为什么它有效

 在每个位置，算法都保持构造字符串的当前后缀从不包含的不变量$K$连续的相同字符。 如果我们到达$K$在一次运行中与原始字符连续匹配，如果不翻转而继续匹配，将立即违反约束，因此强制翻转。 当不违反约束时，保留原始字符始终是最佳选择，因为它不会增加成本。 因此，每次翻转都完全对应于强制修正，从而确保最小化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    K, S = input().split()
    K = int(K)
    n = len(S)
    
    res = []
    flips = 0
    
    i = 0
    while i < n:
        j = i
        while j < n and S[j] == S[i]:
            j += 1
        
        seg_len = j - i
        
        cnt_same = 0
        current_char = S[i]
        
        for idx in range(i, j):
            if cnt_same == K - 1:
                # we cannot extend run, must flip
                new_char = '1' if current_char == '0' else '0'
                res.append(new_char)
                flips += (new_char != S[idx])
                cnt_same = 1
                current_char = new_char
            else:
                res.append(current_char)
                flips += (current_char != S[idx])
                cnt_same += 1
        
        i = j
    
    print(flips, ''.join(res))

if __name__ == "__main__":
    solve()
```实现首先解析$K$和字符串，然后迭代相同字符的最大段。 在每个段内，它贪婪地构建输出，同时确保没有相同的输出字符达到长度$K$。 柜台`cnt_same`跟踪当前输出运行的长度。 当它达到$K-1$，下一个位置必须翻转到相反的位以防止违规。 

一个微妙的实现细节是，通过将所选输出字符与该位置的原始字符串进行比较来计算翻转。 即使构造的字符由于强制交替而不同，这也确保了正确性。 另一个重要的点是重置`cnt_same`翻转后，由于运行身份发生变化。

 ## 边缘情况

 一个关键的边缘情况是当$K=2$，因为每对相等的字符都是无效的。 用于输入`2 0000`，算法立即翻转每隔一个字符，产生类似`0101`。 这个不变量仍然成立，因为我们永远不允许两个相同的相邻输出。 

另一个边缘情况是一个长的均匀字符串，带有大的$K$， 例如`5 0000000000`。 该算法只会翻转一次$K$字符，以最小的中断产生长的有效块。 该跟踪证实翻转恰好发生在强制边界处，而不是更早发生。 

当交替模式已经满足约束时，就会出现最后的边缘情况。 为了`3 010101`，计数器永远不会达到强制阈值，因此不会发生翻转，并且输出与输入相同，从而确认该算法从未引入不必要的修改。
