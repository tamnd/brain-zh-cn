 ## 解决方案

 ## 问题理解

 我们得到了一组不同的整数，每个整数都可以被视为一个 n 位掩码。 我们构建一个图，其顶点就是这些数字，并且只要两个顶点的按位与为零，我们就连接两个顶点。 换句话说，如果两个数字不共享任何均为 1 的位位置，则这两个数字是相邻的。 

任务是确定该图有多少个连通分量。 

重要的结构约束是 n 最多为 22，这意味着每个数字都存在于大小最多为 2²² 的宇宙中。 这足够小，我们可以将位子集视为整个幂集上的状态和推理，但也足够大，以至于不可能在 m 至 2²² 上进行简单的成对图构造。 

一个简单的解释是建议显式构建图并在所有对上运行 DFS 或 DSU。 这会立即遇到麻烦，因为对的数量为 m²，在最坏的情况下约为 2⁴⁴ 操作，远远超出了任何可行的限制。 

如果我们只尝试将每个节点连接到几个任意的补充，则会出现更微妙的故障模式。 例如，如果我们贪婪地将一个数字连接到单个不相交的伙伴，我们很容易错过通过中间节点的传递连接。 一个小例子说明了这一点：

 输入：```
n = 3
a = [1, 2, 4]
```这里每对都有 AND 零，因此图是完全连接的，答案是 1。任何仅将每个节点连接到单个补集或使用不完整邻居生成的方法都可能无法捕获完整的团结构。 

关键的困难在于邻接是由全局位约束定义的，而不是给定列表中的局部结构。 

## 方法

 直接图构造检查所有对并链接那些具有不相交位掩码的对。 这是正确的，但当 m 很大时不可行。 每个边缘测试的时间复杂度为 O(1)，但有 O(m²) 对，因此总工作量很快就会退化。 

关键的观察是该图不是任意的。 每个节点都连接到其位掩码完全位于其补码掩码内的所有节点。 这表明要根据位的子集而不是成对比较来思考。 

我们可以翻转视角，而不是从每个节点探索边缘：将整个 2ⁿ 宇宙视为状态空间，并在子集上使用类似筛子的传播。 中心思想是，只要可以通过不相交的掩码连接，就将所有可到达的节点统一在同一组件下，这对应于遍历位掩码空间中的补集。 

我们预处理存在的掩码，然后使用 DFS 在位掩码补空间上传播连接性。 每次我们访问一个掩码时，我们都会尝试移动到输入集中存在的其补码的所有子掩码。 这避免了在任意对之间显式构建边。 

效率的提高来自于用结构化子集遍历替换成对检查。 每个掩码通过其补码的子掩码生成转换，并且在仔细摊销时，22 位空间上的子集枚举是可行的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解图| O(m²·n) | O(米) | 太慢了 |
 | 补空间上的子掩码 DFS | O(m·2^(n/2)) 摊销 | O(2^n) | O(2^n) | 已接受 |

 ## 算法演练

 1. 我们将所有给定的数字存储在大小为 2ⁿ 的完整位空间上的布尔数组或哈希集中。 这允许 O(1) 成员资格检查。 此步骤是必要的，因为后续转换取决于查询候选掩码是否存在。 
2. 我们在同一空间上维护一个已访问数组，以确保每个数字都准确地分配给一个连接的组件。 这可以防止重新访问状态并保证可到达状态的线性摊销。 
3. 我们迭代所有输入数字。 对于每个尚未访问过的数字，我们从它开始 DFS 并递增组件计数器。 
4. 在节点 x 的 DFS 内部，我们计算其 n 位内的补码掩码，定义为所有位设置为 1 XOR x。 该补码表示允许出现在 x 的邻居中的所有位。 
5. 我们枚举该补集的所有子掩码。 每个子掩码 y 表示与 x 不相交的候选节点。 如果 y 存在于输入集中并且未被访问，我们将其标记为已访问并从 y 继续 DFS。 子掩码枚举是使用标准技巧完成的：从补码开始，重复移动到 (子掩码 - 1) 和补码。 
6. 因此，DFS 通过重复的不相交转换扩展到所有可到达的节点，从而有效地发现全连接组件。 

### 为什么它有效

 核心不变量是 DFS 精确地探索了“可以通过成对不相交的位掩码链进行连接”关系的闭包。 图中的任何边都对应于有效的转换，因为邻接是由不相交定义的。 相反，任何遍历步骤仅遵循有效边，因为补集的每个子掩码都与当前节点不相交。 由于每个可到达的节点必须通过某种不相交的中间掩码序列进行连接，并且 DFS 会毫无遗漏地探索所有此类有效的转换，因此每个组件都会被恰好发现一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
arr = list(map(int, input().split()))

N = 1 << n
present = [False] * N
vis = [False] * N

for x in arr:
    present[x] = True

sys.setrecursionlimit(10**7)

def dfs(x):
    vis[x] = True
    comp = (~x) & (N - 1)

    sub = comp
    while True:
        if present[sub] and not vis[sub]:
            dfs(sub)
        if sub == 0:
            break
        sub = (sub - 1) & comp

ans = 0

for x in arr:
    if not vis[x]:
        ans += 1
        dfs(x)

print(ans)
```该解决方案依赖于大小为 2ⁿ 的完整位掩码域，这是可行的，因为 n ≤ 22。DFS 使用递归，但如果考虑递归深度，则可以转换为显式堆栈。 关键的实现细节是正确的子掩码枚举：从完整补码开始并重复应用`(sub - 1) & comp`，确保所有子集都被访问一次。 

一个微妙的点是掩蔽`(~x) & (N - 1)`，它将补码限制为 n 位。 如果没有这个，Python 的无限位整数将在有效域之外引入不正确的转换。

 ## 边缘情况

 当一个数字在集合中没有有效的邻居时，就会出现一种边缘情况。 例如，如果n = 3并且输入为[7]，则补码为000，并且DFS仅访问自身。 由于输入中不存在补集的子掩码，该算法正确地计算了一个孤立分量。 

另一种情况是许多数字共享稀疏位模式。 例如，当 n = 4 和像 1、2、4、8 这样的数字时，每个的补集包含许多子掩码，但只有一些存在于输入中。 DFS 仍然正确地使用以下方式限制遍历`present`数组，确保不存在的掩码不会扩展组件。 

最后一个微妙的情况是包含零。 由于零与所有数字都不相交，因此它成为一个中心。 在这种情况下，从 0 开始的 DFS 会探索每个当前节点，因为每个掩码都是其补码（所有位集）的子掩码。 该算法自然地将整个集合折叠成一个组件，以匹配图结构。
