 ## 解决方案
 ## 问题理解

 我们有两个相同大小的网格。 每个单元格位置包含一对数字，一个在第一个矩阵中，一个在第二个矩阵中。 唯一允许的操作是交换矩阵之间同一坐标处的两个数字。 因此，对于每个位置，我们可以独立决定矩阵 A 中的值是保留在那里还是移动到矩阵 B，反之亦然。 

在做出这些本地交换决策之后，两个结果矩阵都必须满足强排序条件。 每行必须严格从左到右递增，每列必须严格从上到下递增。 

关键的限制是互换只能按位置进行。 位置之间没有移动，这意味着每个单元格恰好贡献两个候选值，我们选择其中一个作为第一个矩阵，另一个自动转到第二个矩阵。 

这些限制总共允许最多 2500 个单元。 这立即排除了任何基于排列或指数的分配搜索。 然而，由于每个单元都是二元选择独立的，因此贪婪构造或局部一致性检查是合理的。 

天真的直觉的一个微妙的失败案例是假设我们可以在没有协调的情况下贪婪地首先修复行或首先修复列。 例如，如果我们总是将较小的值分配给每个单元格中的矩阵 A，则稍后可能会破坏列排序。 同样，独立地按行优化可能会破坏列的单调性。 

核心困难在于每个单元决策同时影响行约束和列约束。 

## 方法

 暴力方法会将每个单元视为二元决策并尝试所有$2^{nm}$作业。 对于每个分配，我们将检查两个矩阵是否满足严格的行和列增加条件。 这是正确的，但即使对于中等大小也是完全不可行的，因为配置数量随着 2500 个位置呈指数增长。 

关键的观察是，我们实际上并不关心哪个矩阵最终得到哪个值，我们只需要两个矩阵都增加。 在每个位置，我们总是有两个值。 一个将进入矩阵 A，另一个将进入矩阵 B。因此问题变为：我们是否可以选择一种分配，使得两个结果网格都在两个维度上排序？ 

现在考虑一个固定单元。 如果我们将较大的值放入矩阵 A，则矩阵 B 会得到较小的值。 如果我们做相反的事情，矩阵 A 得到较小的值。 因此，每个单元格都让我们可以选择这对单元格对两个矩阵的贡献方向。 

关键的见解是，我们可以使用贪婪扫描顺序同时构建两个矩阵，确保与已经固定的邻居的一致性。 如果我们从左到右、从上到下逐行处理网格，那么在决定单元格时，唯一重要的约束是两个矩阵中的左邻居和上邻居。 

在每个单元中，我们尝试该对的两个方向，并检查它们是否保持两个矩阵相对于已分配的邻居有效。 由于约束是局部的且单调的，因此这种贪婪传递就足够了。

 ## 算法演练

 我们定义两个相同大小的结果矩阵 A 和 B。 

我们按行优先顺序处理单元格。 

1. 对于每个单元格$(i, j)$，我们有一对$(a_{ij}, b_{ij})$。 我们考虑两个分配：要么 A 得到$a_{ij}$, B 得到$b_{ij}$，或者 A 得到$b_{ij}$, B 得到$a_{ij}$。 如果存在解决方案，则必须选择其中之一。 
2. 我们测试是否分配$a_{ij}$到 A 和$b_{ij}$to B 对于已填充的左邻居保留严格的递增条件$(i, j-1)$和上邻居$(i-1, j)$。 该检查仅是本地的，因为未来的小区尚未确定。 
3. 如果第一个分配违反了任何约束，我们将尝试交换的分配。 
4.如果两次分配都失败，我们立即得出不可能的结论，因为没有局部方向可以与已经固定的前缀保持单调性。 
5. 继续，直到分配完所有单元格。 

完成网格后，当且仅当在构建过程中满足所有局部约束时，两个矩阵才有效。 

### 为什么它有效

 在扫描中的任何点，所有先前分配的单元格在两个矩阵中形成有效的递增前缀。 任何未来的单元格只需要尊重其顶部和左侧的邻居，因为这些是唯一可以影响单调网格中的行和列排序的位置。 由于每个约束都在相邻单元之间，因此确保局部一致性可以归纳保证全局正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    A = [list(map(int, input().split())) for _ in range(n)]
    B = [list(map(int, input().split())) for _ in range(n)]

    resA = [[0] * m for _ in range(n)]
    resB = [[0] * m for _ in range(n)]

    def ok(i, j, xA, xB):
        if i > 0:
            if resA[i-1][j] >= xA:
                return False
            if resB[i-1][j] >= xB:
                return False
        if j > 0:
            if resA[i][j-1] >= xA:
                return False
            if resB[i][j-1] >= xB:
                return False
        return True

    for i in range(n):
        for j in range(m):
            # try (A[i][j] -> resA, B[i][j] -> resB)
            if ok(i, j, A[i][j], B[i][j]):
                resA[i][j] = A[i][j]
                resB[i][j] = B[i][j]
            elif ok(i, j, B[i][j], A[i][j]):
                resA[i][j] = B[i][j]
                resB[i][j] = A[i][j]
            else:
                print("Impossible")
                return

    print("Possible")

if __name__ == "__main__":
    solve()
```该解决方案保持两个矩阵同时填充。 辅助函数检查放置所选对是否违反了已固定邻居的严格排序。 由于我们只与左侧和顶部的单元格进行比较，因此我们避免重复扫描整个行或列。 

一个常见的实现陷阱是忘记两个矩阵必须独立满足约束。 如果 B 不增加，则 A 增加是不够的，因此必须在同一个本地决策中检查两者。 另一个微妙的问题是不正确地使用非严格比较。 平等也必须被视为无效，因为条件需要严格增加。

 ## 边缘情况

 关键的边缘情况是，由于先前固定的邻居，一个单元的两种选择都违反了单调性。 例如，如果A中的左邻居是5并且两个候选值都≤5，则两个分配都不能满足严格增加。 该算法立即在该单元格检测到这一点并返回“不可能”。 

另一种边缘情况发生在仅存在一个邻居的第一行或第一列。 该实现正确地避免了检查不存在的索引，并且仅强制执行已定义的约束。 

最后，平等是一个无声的失败源。 如果候选值等于邻居，则必须拒绝它。 该算法明确使用非严格比较（`>=`）在两个矩阵中统一执行此规则。
