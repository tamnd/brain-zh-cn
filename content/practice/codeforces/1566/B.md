[CF 1566B - MIN-MEX 剪切](https://codeforces.com/problemset/problem/1566/B)

 **评分：** 800
 **标签：** 位掩码、构造性算法、dp、贪婪
 **求解时间：** 5m 8s
 **已验证：** 否

 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，并且可以将其分割成任意数量的连续片段。 每个角色必须完全属于一个棋子。 

对于每个部分，我们计算其 MEX。 由于字符串只包含`0`和`1`，只有三个可能的值：

 | 作品内容 | 墨西哥 |
 | ---| ---|
 | 不包含`0`| 0 |
 | 包含`0`但没有`1`| 1 |
 | 包含两者`0`和`1`| 2 |

 我们的目标是选择切割以使所有片段的 MEX 值之和尽可能小。 

所有测试用例的总长度最多为$10^5$。 这意味着我们应该期待一个接近线性时间的解决方案。 二次方法需要大约$10^{10}$最坏情况下的操作，远远超出了极限。 

棘手的部分是了解切割何时有帮助、何时有害。 

考虑字符串`1111`。 整个字符串仅包含`1`s，所以它的 MEX 是`0`。 答案是`0`。 总是尝试创建更多作品的解决方案会错过这一点。 

考虑字符串`0000`。 整个字符串仅包含`0`s，所以它的 MEX 是`1`。 答案是`1`。 将其分成几个全零的部分给出 MEX`1`对于每件作品，只会增加总和。 

考虑字符串`01010`。 整个字符串包含两个数字，所以它的 MEX 是`2`。 粗心的观察可能会表明包含两个数字的每个字符串都有答案`2`。 那是错误的。 我们可以把它剪成`0 | 1010`, 给予`1 + 1 = 2`，但我们不能做得更好。 

现在考虑`100001`。 整个字符串有 MEX`2`，但切割为`1 | 0000 | 1`给出`0 + 1 + 0 = 1`。 答案就变成了`1`。 理解为什么会发生这种情况是解决问题的关键。 

## 方法

 暴力解决方案将尝试所有可能的切割位置集。 长度为一串$n$有$n-1$潜在的剪切位置，并且每个位置可能包含也可能不包含剪切。 这给出了$2^{n-1}$分区。 

对于每个分区，我们可以计算每个部分的 MEX 并保留最小总和。 这是正确的，因为它会检查每个有效答案，但即使对于$n=50$，更不用说$10^5$。 

为了找到一种模式，让我们看看是什么贡献了正成本。 

任何仅包含`1`s 有墨西哥`0`，所以这样的作品是免费的。 

任何包含至少一个`0`至少花费`1`。 

这立即表明我们真正关心的唯一字符是零。 

例如，假设所有零都属于单个连续块`111000111`。 我们可以隔离零块并用全一块包围它：`111 | 000 | 111`成本是`0 + 1 + 0 = 1`。 

现在假设字符串有两个独立的零块，例如`0011100`。 

两个零组不能合并为一个全零块，因为它们之间有一个。 我们有两个选择。 

我们可以将所有内容放在一起，制作一件包含两个数字的作品并付款`2`。 

或者我们可以隔离两个零组：`00 | 111 | 00`这花费`1 + 0 + 1 = 2`。 

无论哪种方式，答案都是`2`。 

这一观察完全说明了问题的特征。 

如果根本没有零，答案是`0`。 

如果恰好存在一个连续的零块，则答案是`1`。 

如果有两个或多个零块，则答案是`2`。 

没有什么比`2`永远是最佳的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n)$|$O(n)$| 太慢了 |
 | 最佳 |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 读取二进制字符串。 
2. 计算有多少个连续的块`0`出现在字符串中。 
3. 如果零块的数量为`0`， 输出`0`。 

该字符串完全由以下部分组成`1`s，所以整个字符串有 MEX`0`。 
4. 如果零块的数量是`1`， 输出`1`。 

我们可以将该零块隔离成仅包含零的一块。 所有剩余的部分仅包含一个并且贡献零成本。 
5. 如果零块的数量至少为`2`， 输出`2`。 

至少存在两个独立的零组。 它们不能合并成一个全零的部分，因为它们将它们分开。 最好的可能成本恰好是`2`。 

### 为什么它有效

 关键的属性是每一个包含零的部分至少贡献`1`到答案。 

如果字符串包含一个零块，则所有零都可以放置在单个全零块内，从而给出总成本`1`。 

如果字符串包含多个零块，我们有两种可能性。 我们可以将一些 1 与 0 放在一起，创建一个 MEX 为`2`，或隔离零块并支付`1`对于每个相关的部分。 任何一种策略都会降低成本`2`，并且任何策略都无法实现成本`1`因为单个全零块无法覆盖多个分离的零块。 

因此，答案仅取决于零块的数量：$$\min(2,\text{number of zero blocks})$$零块等于零的特殊情况会产生答案`0`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        s = input().strip()

        blocks = 0
        n = len(s)

        for i in range(n):
            if s[i] == '0' and (i == 0 or s[i - 1] == '1'):
                blocks += 1

        ans.append(str(min(blocks, 2)))

    sys.stdout.write("\n".join(ans))

solve()
```该实现仅计算连续的零段。 

每当我们看到一个新的零块时，就会开始`0`其前一个字符不存在或等于`1`。 该条件标识每个零运行的第一个字符。 

一旦知道了零块的数量，答案就很简单`min(blocks, 2)`。 这个紧凑的公式自然涵盖了所有情况：

 如果`blocks = 0`，结果是`0`。 

如果`blocks = 1`，结果是`1`。 

如果`blocks >= 2`，结果是`2`。 

不需要额外的处理。
