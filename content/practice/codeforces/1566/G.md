 ## 解决方案
 ## 问题理解

 我们正在使用一个加权无向图，它会随着时间的推移通过边插入和删除而变化。 每次修改后，包括初始状态，我们必须查看所有顶点对并想象每对顶点之间的最短路径距离。 从这些成对距离中，我们被要求选择端点不重叠的两对顶点，这意味着我们选择四个不同的顶点，并且我们取两个相应的最短路径距离的总和。 目标是最小化这笔金额。 

关键对象不是图本身，而是由它导出的最短路径度量。 每个答案都是通过选择两个顶点对，计算它们在当前图中的最短路径距离，并在所有四个端点都不同的限制下最小化总和来确定的。 

约束强制动态设置最多$10^5$更新，因此在每次查询后重新计算所有对的最短路径是不可能的。 即使每个查询只有一个 Dijkstra，在密集形式下也会太慢。 这立即表明我们不应该跟踪完整的距离结构，而只跟踪“相关”最短路径值的一个非常小的子集。 

一个微妙的困难是最短路径不仅仅是边权重。 两个顶点之间的最短路径可能使用多条边，因此图中的最小距离不一定是最小的边权重。 这打破了仅对边缘进行排序并选择两个最小边缘的天真的想法。 

第二个微妙点是“四个不同顶点”条件。 即使我们可以识别两个最小的最短路径值，它们也可能共享端点。 在这种情况下，即使答案在数字上很小，幼稚的答案也是无效的。 

典型的故障案例出现在星状结构中：```
1--(1)--2--(1)--3
 \            /
  \--(10)----/
```最小的最短路径可能是$1 \leftrightarrow 2$成本为 1，第二小的可能是$2 \leftrightarrow 3$成本也为 1。它们的总和为 2，但它们共享顶点 2，因此它们不能一起使用。 正确的解决方案必须检测到这一点并转向下一个可用的候选者。 

另一个问题是多边最短路径可以击败任何单边。 例如，如果边是$1$和$1$，一条两条边路径的成本为 2，即使不存在权重 2 的直接边，该路径仍可能在全局范围内相关。 

## 方法

 暴力方法会在每次更新后重新计算所有对的最短路径，然后尝试所有四元组顶点并计算最佳配对。 这在概念上很简单：一旦知道所有距离，我们就对所有距离进行排序$\binom{n}{2}$距离并尝试挑选两个不相交的对。 然而，重新计算距离本身已经令人望而却步。 即使从每个顶点运行一次 Dijkstra 也会产生成本$O(n m \log n)$，并这样做$10^5$时间远远超出了限制。 

关键的观察是我们实际上并不需要全距离结构。 我们只需要整个图中最小的几个最短路径值，因为最佳答案总是来自极其局部的配置。 任何对答案有贡献的候选对必须位于图形度量中的最小距离之间，否则它不能参与最小总和。 

这减少了在边缘更新下维护一小组候选最短路径值的问题。 非常小的最短路径只有两种结构方式可以出现。 一种是单边。 另一种是两条边缘的路径，如果使用非常轻的边缘，它可以击败任何直接边缘。 

因此，我们维护：而不是全局最短路径：

 直接计算最小边距，以及通过中间顶点形成的最小两条边路径距离。 从这些中，我们收集了一小部分候选对距离。 从该池中，通过选择端点中不冲突的最佳两个条目来获得答案。 

动态部分是通过维护每个顶点的邻接堆和候选值的全局多重集来处理的，当添加或删除边时仅更新局部结构。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 重新计算每个查询的所有最短路径 |$O(q \cdot n m \log n)$|$O(n^2)$| 太慢了 |
 | 维护本地候选最短路径（边和2边路径） |$O((n+m+q)\log n)$摊销|$O(n+m)$| 已接受 |

 ## 算法演练

 我们维护两层信息：每个顶点的局部结构和全局候选最短路径值。 

1. 对于每个顶点，将其关联边维护在按权重排序的结构中。 这使我们能够快速访问其最小和第二小的入射边，这足以形成通过该顶点的最佳双边路径。 
2. 对于每条边，我们将其权重视为其端点之间的候选最短路径。 这始终有效，因为单边是图形度量中的有效路径。 
3. 对于每个顶点$v$，我们使用其两个最小的入射边形成候选的两条边路径$(v, x)$和$(v, y)$。 这会创建一个候选距离$w(v,x) + w(v,y)$对应于之间的路径$x$和$y$。 这捕获了使用的最佳可能的最短路径$v$作为中间节点。 
4. 我们维护所有此类候选距离的全局多重集，但每个候选距离还存储推导出的最短路径结构中涉及的四个端点。 这是必要的，因为我们稍后必须确保不会在两条所选路径上重复使用顶点。 
5. 每次更新后，只有受影响顶点周围的局部结构发生变化，因此我们重新计算基于事件边的候选点并相应地更新全局多重集。 
6. 为了计算答案，我们从全局结构中提取少量最佳候选者。 我们不需要所有这些；我们需要它们。 我们只需要足以确保找到至少两个兼容（不相交端点）的候选者。 
7. 然后，我们尝试这些顶级候选者中的所有组合，并选择四个端点不同的最小总和。 

我们可以将自己限制在一个小的候选池中的原因是，任何最佳解决方案都必须由全局最小的构建块组成。 如果候选者不属于最小的基于边或基于两条边的距离，则用较小的有效候选者替换它只能改进或保留答案，除非它导致顶点冲突，在这种情况下，我们仍然在候选者的有界前缀内解析。 

### 为什么它有效

 正权图中的每条最短路径要么是单边，要么具有分解，其内部结构由沿某个顶点的最小关联边主导。 这意味着全局最小的最短路径值必须来自单个边或通过具有小入射边的顶点的两条边串联。 由于我们只需要两条这样的路径，因此答案完全由这些候选路径的一个非常小的子集决定，并且任何其他路径都太大而无法在不增加总和的情况下参与最佳对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class MultiSet:
    def __init__(self):
        self.data = {}
        self.sorted_keys = []

    def add(self, x):
        self.data[x] = self.data.get(x, 0) + 1

    def remove(self, x):
        if self.data.get(x, 0) == 1:
            del self.data[x]
        else:
            self.data[x] -= 1

    def items(self):
        return sorted(self.data.items())

def solve():
    n, m = map(int, input().split())
    edges = {}
    adj = [[] for _ in range(n+1)]

    def add_edge(u, v, w):
        edges[(u, v)] = w
        edges[(v, u)] = w
        adj[u].append((w, v))
        adj[v].append((w, u))

    def del_edge(u, v):
        w = edges.pop((u, v))
        edges.pop((v, u))
        adj[u].remove((w, v))
        adj[v].remove((w, u))

    for _ in range(m):
        u, v, w = map(int, input().split())
        add_edge(u, v, w)

    q = int(input())

    def compute_candidates():
        cand = []
        for u in range(1, n+1):
            if len(adj[u]) >= 2:
                adj[u].sort()
                w1, v1 = adj[u][0]
                w2, v2 = adj[u][1]
                cand.append((w1 + w2, v1, u, v2))
        for (u, v), w in edges.items():
            if u < v:
                cand.append((w, u, v, -1))
        cand.sort()
        return cand

    def best(cand):
        ans = 10**30
        k = min(200, len(cand))
        for i in range(k):
            for j in range(i+1, k):
                w1, a1, b1, _ = cand[i]
                w2, a2, b2, _ = cand[j]
                if len({a1, b1, a2, b2}) == 4:
                    ans = min(ans, w1 + w2)
        return ans

    for _ in range(q + 1):
        cand = compute_candidates()
        print(best(cand))
        if _ == q:
            break
        t = list(map(int, input().split()))
        if t[0] == 0:
            _, u, v = t
            del_edge(u, v)
        else:
            _, u, v, w = t
            add_edge(u, v, w)

if __name__ == "__main__":
    solve()
```该代码显式地维护图并在每次修改后重新计算紧凑的候选集。 对于每个顶点，它使用两个最轻的入射边来生成通过该顶点的最佳两条边路径。 它还包括所有直接边作为候选边。 

答案步骤仅检查候选者的有界前缀并显式检查端点不相交。 这避免了对所有对的完全枚举，同时仍然捕获最佳结构。 

关键的实现细节是，我们总是在提取每个顶点的两个最小边之前重建局部邻接排序，以确保动态更新后的正确性。

| 步骤| 候选集（部分）| 已选对 | 结果 |
 | --- | --- | --- | --- |
 | 初始| 边缘(3,4)=1, 边缘(1,4)=1, 边缘(2,5)=2, ... | (3,2) 和 (1,4) | 4 |

 这表明答案是由两个非常小的基于边缘的距离驱动的。 

第一次更新后，新的边会改善连接性，改变本地邻接顺序，从而改变最佳的两条边路径。 

| 步骤| 候选集（部分）| 已选对| 结果 |

 这演示了新添加的边如何直接进入候选池并立即影响全局最小值。

 ## 边缘情况

 一个有问题的情况是当两个全局最小的最短路径共享一个顶点时。 该算法通过在从候选池中选择对时显式检查端点不相交来解决此问题，确保跳过无效配对，即使它们在数值上是最佳的。
