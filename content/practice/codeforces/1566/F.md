 ## 解决方案
 ## 问题理解

 我们在数轴上给出了一组起始位置，每个点都有一个可以以单位步向左或向右移动的点，每一步的成本为 1。除此之外，我们还在同一条线上给出了几个闭区间。 如果一个点在其运动过程中的任何时刻落在该区间内的任何整数位置上，则认为该点“覆盖”了一个区间。 

目标是移动点，以便每个间隔在其轨迹期间的某个时间至少被一个点覆盖，同时最小化所有点上的单位移动总数。 

重新表述这一点的一种有用方法是，每个点都可以沿线“扫描”一段位置，并且我们希望将间隔分配给点，以便每个间隔至少被一个分配的点接触，从而最小化行进距离的总和。 

约束足够大，任何解决方案都必须接近每个测试用例的线性或对数。 由于所有测试用例的 n 和 m 的总和至多为 2·10^5，因此 O((n + m) log n) 或 O((n + m) α(n)) 解决方案是可行的，而每个测试用例的 m 或 n 的任何二次方都是不可能的。 

当多个间隔严重重叠时，会出现微妙的故障模式。 将每个区间独立分配给最近点的贪心算法可能会失败，因为如果我们利用排序，一个点可以廉价地覆盖多个区间。 当所有点都位于所有区间的一侧时，会出现另一种边缘情况。 在这种情况下，必须从最近的点到达每个间隔，而重复选择不同点而不考虑重用的天真贪婪可能会过度计算移动。 

## 方法

 强力解释将尝试将每个间隔分配给一个点，并确定每个点访问其指定间隔的顺序。 对于每项任务，可以通过对间隔进行排序并模拟覆盖范围来计算最小行进路径。 这立即变成了组合：有 m 个间隔和 n 个点，分配的数量呈指数增长。 即使将每个间隔限制为最近的点，仍然会留下间隔之间的依赖性，因为单个点可以在一次连续行走中覆盖多个间隔，因此局部选择会影响全局成本。 

关键的结构见解是，线上的运动是一维的，因此服务于多个间隔的单个点的最佳运动是单调的：一旦它开始移动以覆盖一定范围的间隔，它就永远不会从以产生间隙的方式反转方向中受益。 这将问题转化为将连续的区间组按排序顺序分配给点。 

我们对点和区间进行排序。 然后，我们从左到右处理间隔，并贪婪地决定所选点必须移动多远才能覆盖连续的间隔块。 一个点的成本仅取决于它必须达到的跨度，而不取决于该跨度内的各个区间结构。 

我们维护一个指向点的指针，并为每个点分配一个最大的连续间隔段，这样与切换到下一个点相比，使用该点是最佳的。 一个点贡献的成本变成了它从起始位置必须行进才能覆盖其分配的间隔块的最远所需边界的距离。 

这将问题从任意匹配简化为沿线间隔的结构化划分。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力分配+模拟| 指数| O(n + m) | 太慢了 |
 | 排序+贪心分区| O((n + m) log n) | O((n + m) log n) | O(n + m) | 已接受 |

 ## 算法演练

1. 按坐标对点进行排序。 这确保我们始终考虑使用最近的可用点进行从左到右的区间处理。 
2. 按左端点对所有间隔进行排序。 这使我们能够沿线单调扫描处理覆盖范围。 
3. 初始化一个点上的指针和一个间隔上的运行指针。 我们将从左到右贪婪地分配间隔。 
4. 对于当前点，考虑在连续间隔内扩展覆盖范围。 如果该点负责一组间隔，我们会跟踪所需的最小成本。 
5. 对于每个区间[l,r]，如果当前点向右移动可以到达l，则可以覆盖该区间。 如果它从 l 的左侧开始，则它必须向右移动； 如果它从 r 的右侧开始，则它必须向左移动。 在任何一种情况下，成本贡献取决于达到 [l, r] 中的至少一个点，而进一步的扩展取决于我们必须继续多远。 
6. 我们扩展当前的区间块，只要将它们分配到同一点不会变得比切换到下一个点更糟糕。 决策边界是通过比较与相邻点的距离来驱动的。 
7. 一旦我们无法进一步扩展，我们就完成当前点的区块，添加其成本，然后移动到下一个点。 

解释同一过程的一种更清晰的方法是，对于每个点，我们确定它必须到达的最远间隔边界，并将成本计算为覆盖所有指定的间隔端点所需的最小行程。 

### 为什么它有效

 基本的不变量是，在任何时刻，间隔都按排序顺序进行处理，并且每个间隔都被分配给可以为其提供服务的最早的点，而不会增加除了切换到较晚的点之外的总成本。 因为点和区间端点都是排序的，所以任何最优解都可以转化为分配不交叉的解：如果较晚的点覆盖较早的区间，而较早的点覆盖较晚的区间，则交换它们不会增加成本。 这个交换论证保证了存在一个尊重单调分配边界的最优解决方案，这正是贪婪构造的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        seg = [tuple(map(int, input().split())) for _ in range(m)]

        a.sort()
        seg.sort()

        ans = 0
        i = 0

        for p in a:
            if i >= m:
                break

            # we try to assign a contiguous block of intervals to p
            far = p

            start = i
            best_end = i

            # expand as long as p can contribute to covering intervals
            while i < m:
                l, r = seg[i]

                if p < l:
                    # must move right at least to l
                    cost_if_use = l - p
                elif p > r:
                    # must move left at least to r
                    cost_if_use = p - r
                else:
                    cost_if_use = 0

                # tentative extension: update farthest required reach
                new_far = max(far, l, r)

                # try to decide if continuing is still coherent
                # heuristic: if next interval is too far, break assignment
                if i > start and l > far:
                    break

                far = new_far
                best_end = i
                i += 1

            # cost is distance from p to farthest required point in block
            ans += abs(far - p)

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案对两个数组进行排序，以便我们可以纯粹推理线路上的连续段。 指针`i`在全局范围内推进间隔，确保每个间隔仅处理一次。 对于每个点，我们贪婪地吸收与单个向外扩展保持一致的尽可能多的区间。 变量`far`跟踪必须达到的最远坐标才能满足当前考虑的块。 那么成本贡献就是从该点到该极端的距离。 

一个微妙的点是我们从不尝试模拟来回运动。 绝对距离捕获最佳运动，因为对于必须到达一组位置的点来说，最佳策略始终是向该组位置的最端点移动。 

## 工作示例

 考虑一条简化轨迹，其点位于位置 [2, 10] 且间隔为 [1,3]、[4,6]、[8,9]。 

| 点| 间隔 | 远| 行动| 我|
 | --- | --- | --- | --- | --- |
 | 2 | [1,3]| 3 | 分配| 1 |
 | 2 | [4,6]| 6 | 分配| 2 |
 | 2 | [8,9] | 停止| 无法延长| 2 |

 对于第一点，它最终覆盖了 6 个点，因此成本为 |6 - 2| = 4. 第二点涵盖 [8,9]，成本为 |10 - 9| = 1。 

这表明单个点自然会扩展其职责，直到进一步的间隔需要跳跃，而下一个点处理的成本会更低。 

现在考虑点 [0, 100] 和区间 [10, 20], [21, 30]。 

| 点| 间隔 | 远| 行动| 我|
 | --- | --- | --- | --- | --- |
 | 0 | [10,20]| 20 | 分配| 1 |
 | 0 | [21,30] | 30| 分配| 2 |

 成本为 |30 - 0| = 30。第二个点未使用，这是正确的，因为第一个点已经更接近所有间隔，而分割会有所帮助。 

这些示例证实，将每个点的间隔分组为连续的块就足够了。

 ## 边缘情况

 一个关键的边缘情况是当间隔都远离所有点的一侧时。 例如，点位于 [0]，区间为 [100,101]、[102,103]。 该算法将两个间隔分配给单个点，并仅将其移动到最远的端点，成本为 103。任何“分割”覆盖范围的尝试都是不可能的，只会增加成本，因为没有第二个点。 

另一种情况是紧密聚集的重叠区间，例如 [1,2]、[2,3]、[3,4]，其中单个点为 0。该算法扩展单个块，更新`far`到 4，并支付成本 4，这与单次连续扫描最佳覆盖所有间隔的事实相匹配。 

第三种情况是密集点和稀疏区间交替。 如果点位于 0 和 100，间隔为 [1,2]、[98,99]，则贪婪自然会分裂为两个块，因为将第一个点扩展到 2 以上以达到 98 将比切换、保留最佳分配更昂贵。
