 ## 解决方案
 ## 问题理解

 我们的任务是安排座位`nm`人们在电影院与`n`行和`m`列，每排的座位从左到右连续编号。 每个人都有一个“视力水平”，视力水平较低的人应该获得更好的座位，这些座位被定义为指数较低的座位。 按照这个规则分配座位后，人们按照原来输入的顺序进入电影院。 当每个人从他们的排的开始走到他们分配的座位时，不便被计为他们必须经过的已占用座位的数量。 目标是分配座位，从而最大程度地减少对所有人造成的总不便。 

问题约束允许`n`和`m`最多 300 个，这意味着单个测试用例最多 90,000 个席位。 在所有测试用例中，总人数不超过 100,000 人。 这排除了朴素的 O((nm)^2) 解决方案，但 O(nm log(nm)) 方法是可行的，因为对 100,000 个元素进行排序并迭代它们可以轻松地在 1 秒的时间限制内完成。 

当多个人具有相同的视线水平时，就会出现不明显的边缘情况。 如果这些人随意排成一排，他们可能会低效地互相阻挡。 例如，一排 4 个座位和视线水平`[1, 1, 1, 1]`，如果我们按照输入顺序从左到右分配座位，则输入中较晚的人可能必须通过比必要的更多的占用座位。 最佳策略应该最大限度地减少每行内从左到右的拥塞。 

## 方法

 蛮力方法很简单：根据视线水平对人们进行排序，并尝试将他们排入座位的各种排列。 对于每个座位排列，模拟所有人的进入并计算不便之处。 这是正确的，因为它遵循视觉水平的排序。 然而，这需要 O((nm)!) 次排列，并且每个排列需要 O(nm^2) 次工作来进行模拟，这对于我们的约束来说在计算上是不可能的。 

关键的见解来自于观察，即最大限度地减少每一排的不便可以减少到小心地将人们放置在相同的视线水平上。 由于一排的每个人都是从左到右进入的，因此如果我们将具有相同视线水平的人从最右边的可用座位开始并向左填充，则可以最大程度地减少不便。 这确保了一个人不会超越任何具有相同视线水平的先前就座的人，如果我们从左到右填充，这是不可避免的。 因此，算法根据视力水平对所有人进行排序，将他们分成不同大小的块`m`与每一行相对应，并且在每一行内，将具有相同视线水平的人按从右到左的顺序放置，以尽量减少彼此交叉。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O((nm)！ * nm) | O(纳米) | 太慢了 |
 | 最佳 | O(nm log(nm)) | O(nm log(nm)) | O(纳米) | 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 对于每个测试用例，请阅读`n`,`m`，以及视线级别列表。 
2. 创建元组列表`(sight_level, original_index)`对于所有人并首先排序`sight_level`，然后由`original_index`。 按原始索引排序可确保相同视线水平的确定性决胜局。 
3. 初始化一个代表电影院座位的 2D 列表，其中`n`行和`m`列。 
4. 对于每一行，取下一行`m`已排序列表中的人。 在该组中，按视线水平对它们进行排序，然后从右到左分配座位。 这可以防止具有相同视力水平的人不必要地交叉。 
5. 对于每一排，从左到右模拟座位，计算每个人经过的已占用座位的数量。 使用简单的二分搜索或直接计数来查找每个人分配的座位之前已占用的座位数。 
6. 对所有行的不便之处求和并打印结果。 

原理：通过从右到左填充具有相同视力水平的人的每一行，我们可以保证在一行内，没有人超过具有相同视力水平的另一个人。 由于视力水平较低的人会被全局排序到较早的座位索引，因此座位分配也遵循以下总体要求：`s_i < s_j`每当`a_i < a_j`。 因此，在这些限制下，总的不便被最小化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        people = [(a[i], i) for i in range(n * m)]
        people.sort(key=lambda x: (x[0], x[1]))

        # Fill rows
        seating = [[None]*m for _ in range(n)]
        idx = 0
        for i in range(n):
            row_people = people[idx:idx+m]
            # Sort by index in reverse within the row for same level people
            row_people.sort(key=lambda x: x[1], reverse=True)
            for j, person in enumerate(row_people):
                seating[i][j] = person
            idx += m

        total_inconvenience = 0
        for row in seating:
            occupied = [0]*m
            for j in range(m):
                # Count number of already seated people to the left
                total_inconvenience += sum(occupied[:j])
                occupied[j] = 1

        print(total_inconvenience)

if __name__ == "__main__":
    solve()
```该解决方案完全遵循算法。 按原始索引排序可确保行内的确定性放置。 这`occupied`当我们模拟入场时，列出已被填满的座位。 计算左侧占用座位的总数会给该人带来不便。 

## 工作示例

 对于输入：```
3 2
1 1 2 2 3 3
```按视力水平对人进行排序：`[(1,0),(1,1),(2,2),(2,3),(3,4),(3,5)]`。 

第一排座位（同层从右到左）：索引`[1,0]`第2排座位：`[3,2]`第3排座位：`[5,4]`不便之处：

 | 行| 座位索引 | 每个座位的不便| 总计 |
 | ---| ---| ---| ---|
 | 1 | 1,0 | 0,0 | 0 |
 | 2 | 3,2| 0,0 | 0 |
 | 3 | 5,4 | 0,0 | 0 |

 总不便 = 0，与样本输出匹配。 

另一个输入：```
2 2
1 1 2 1
```排序的人：`[(1,0),(1,1),(1,3),(2,2)]`第 1 行（同一级别从右到左）：`[1,0]`第 2 行：`[3,2]`第 1 排不便：座位 1 通行 0 已占用，座位 0 通行 1 → 总计 1

 第 2 行不便：均为 0

 总计 = 1
