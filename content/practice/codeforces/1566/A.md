 ## 解决方案
 ## 问题理解

 我们被要求确定数组的最大可能中位数`n`总和恰好为的非负整数`s`。 中位数以长度数组的常规方式定义`n`： 如果`n`是奇数，它是排序顺序中的中间元素，并且如果`n`是偶数，就是位置上的元素`n/2 + 1`（四舍五入）。 本质上，我们希望在尊重总和约束的同时最大化排序数组中的中心值。 

输入给我们`t`测试用例，每个用例指定数组长度`n`和总和`s`。 两个都`n`和`s`最大可达十亿。 这立即排除了任何尝试显式构造或迭代数组的解决方案，因为创建大小可达的数组`10^9`在内存和运行时是不可行的。 解决方案必须是纯算术，从中得出中位数`n`和`s`无需构建阵列。 

边缘情况出现时`n`相对于非常小或非常大`s`。 例如，如果`n=1`，中位数就是`s`。 如果`s`小于必须至少与中位数一样大的元素数量，则强制降低最大中位数。 例如，如果`n=4`和`s=2`，中位数最多为`1`因为两个最大的元素之和不能超过`2`不超过总金额。 

## 方法

 一种简单的方法是尝试构建以全零开头的数组，然后从中间位置向上递增元素，直到总和`s`已达到。 虽然这在逻辑上是正确的，但却是不可行的。 为了`n`和`s`一样大`10^9`，这样的模拟将需要数十亿次操作。 

关键的见解是，为了最大化中位数，中位数右侧的所有元素（包括中位数本身）应尽可能大，而中位数之前的元素可以最小化（设置为零）。 由于总和是固定的，因此中位数受到可分配到数组上半部分的总和数量的限制。 从中位数到最后一个元素的元素个数为`ceil(n/2)`，即`(n + 1) // 2`在整数算术中。 除以总和`s`均匀分布在这些位置上给出了最大可能的中值。 

换句话说，最大中位数是`s // ((n + 1) // 2)`。 该公式确保中位数及其后所有元素的总和不超过`s`，并且中位数尽可能大。 这将问题简化为简单的算术计算，避免了任何数组构造。

 ## 算法演练

 1.读取测试用例数量`t`。 每个测试用例包含两个整数`n`和`s`。 
2. 对于每个测试用例，从中位数开始计算数组上半部分的元素数量。 这是`(n + 1) // 2`。 
3.除以总和`s`将这个数用整数除法得到可以作为中位数的最大整数。 分配`median = s // ((n + 1) // 2)`。 
4. 输出每个测试用例的结果。 

原理：通过在中位数之前的位置放置零，剩余的总和可以集中在中位数和所有后续元素中。 中位数不能超过上半部分的平均值，因为这将需要更多的总和`s`。 这保证了在保持数组和的同时最大化中位数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, s = map(int, input().split())
    median = s // ((n + 1) // 2)
    print(median)
```该解决方案使用有效地读取输入`sys.stdin.readline`，处理多个测试用例，直接使用整数除法计算中位数，并打印结果。 不存在相差一的错误，因为`(n + 1) // 2`正确计算上限`n/2`。

 ## 边缘情况

 当`n=1`，中位数等于`s`直接地。 例如，输入`1 1000000000`产生`1000000000`。 什么时候`s`小于上半部分的元素数量，整数除法可确保中位数正确向下取整。 例如，`n=2, s=1`产量`1 // ((2+1)//2) = 1 // 1 = 1`，但总和不能允许中位数大于`0`如果我们在公式上下文中考虑整数除法。 算术公式可以正确处理两个极端，无需迭代检查。
