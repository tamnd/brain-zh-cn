 ## 解决方案
 ## 问题理解

 我们有一排座位，按从左到右递增的顺序标记。 有$m$座位，以及$nm$人们，但自从$n = 1$，我们只有一行长度$m$确切地包含$m$总共人。 

每个人都有一个值，代表他们对可见性的关心程度。 较小的值意味着一个人应该获得更好的座位，这意味着索引较低的座位号。 形式上，如果一个人的视力值严格小于另一个人的视力值，则必须为他们分配严格较小的座位索引。 

人们不会同时坐着。 他们按顺序输入$1$到$m$，每个人从座位上沿着自己的排走$1$直到他们指定的座位。 他们经过的每一个已被占用的座位都会增加一个不便。 

任务是根据视线值引起的排序约束来分配座位，同时最小化这些行走期间交叉的占用座位总数。 

约束条件$n = 1$大大简化了结构。 我们本质上是将人们排列成一系列的位置，但具有由他们的价值观决定的单调性约束。 

所有测试用例的输入大小最多为$10^5$，所以任何解决方案都必须粗略地$O(m \log m)$或每个测试用例更好。 模拟步行或尝试所有任务的二次方法一次太慢$m$达到几千，因为每个安排都已经需要$O(m)$，并且枚举或模拟动态布局内的反转会导致$O(m^2)$行为。 

当许多人具有相同的视觉值时，就会出现微妙的边缘情况。 在这种情况下，他们之间可以按任意顺序分配座位。 仅按值排序并严格从左到右分配而不考虑相等组的天真贪婪可能会意外地假设固定顺序并根据实现进行多计数或少计数反转。 

## 方法

 蛮力策略将尝试将所有有效的人员分配到尊重按视觉值排序的座位。 对于每项分配，我们都会模拟就座过程，并通过检查每个人有多少已就座的人躺在座位左侧来计算总的不便程度。 即使我们将自己限制为与排序一致的赋值，仍然有很多方法可以排列等值元素，并模拟每个赋值的成本$O(m)$。 当许多值相等时，这会导致最坏情况下的阶乘行为。 

关键的简化是分离两种效果。 首先，排序约束迫使我们以非递减的视觉价值顺序来处理人员。 其次，一旦分配顺序确定，一个座位造成的不便正是其左侧先前分配的座位数量。 这相当于计算有多少个之前分配的位置小于当前位置，这是一个类似求逆的量。 

现在结构变得更加清晰：我们将元素一个接一个地放置在一行中，每个放置位置都会贡献其左侧已占用位置的数量。 为了最小化这个总和，我们希望尽早分配占据能够最小化未来阻塞的位置。 具体来说，处理较早（数值较小）的人应该尽可能放在左边，但当数值相等时，我们有灵活性。 

这变成了一个经典的贪婪排序：根据视觉值对人们进行排序，并按升序分配座位，但我们必须在相等的值中仔细选择排序。 正确的方法是处理相等值的组并以任意顺序分配它们，但使用之前分配的左侧座位数来计算它们的贡献。 这可以使用位置上的芬威克树来维护，跟踪哪些座位已经被占用。 

我们遍历排序的人员，对于每个选定的座位，我们计算其之前有多少个已占用的座位。 这是动态集上的标准前缀和查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(m! \cdot m)$|$O(m)$| 太慢了 |
 | 最优（排序+芬威克树）|$O(m \log m)$|$O(m)$| 已接受 |

 ## 算法演练

 1. 按照视力值非降序对所有人进行排序。 

这强制要求，每当一个人的价值小于另一个人时，他们就会首先被处理，如果我们按升序选择座位，他们将收到较小的座位索引。 
2. 维护支持两种操作的座位位置数据结构：将座位标记为已占用，并计算有多少已占用座位严格位于给定位置的左侧。 

座位数组上的 Fenwick 树就足够了，因为它支持对数时间的前缀和。 
3. 按排序顺序迭代人员。 为每个人选择一个座位。 

由于我们希望最大限度地减少未来的拥堵，因此我们在限制范围内从左到右处理座位。 实际上，我们在同等价值的群体中按照指数递增的顺序分配席位。 
4. 对于每个选择的座位索引$s$，查询 Fenwick 树以获取范围内占用的座位数$[1, s]$。 

该值正是当前人必须经过的人数，因为所有先前占用的座位都位于他们的路径上。 
5.将此计数添加到答案中并标记座位$s$正如芬威克树中所占据的那样。 
6. 继续，直到分配完所有人员。 

微妙之处在于，成本仅取决于每次插入之前最终占用的位置集，而不取决于人员的身份。 按值排序保证了可行性，而从左到右的放置则最大限度地减少了未来不必要的前缀密度。 

### 为什么它有效

 在任何时候，将一个人置于某个位置所造成的不便$s$等于已占用位置的数量$[1, s]$。 这与未来的放置无关，因此一旦做出早期选择，每个步骤的贡献都是固定的。 

按视线价值排序可以确保不会有后来的约束迫使价值较小的人陷入比价值较大的人更糟糕的境地。 在相等的值内，交换分配不会违反约束，因此我们可以自由地以任何顺序处理它们，并且贪婪的从左到右处理避免了在座位前缀中创建不必要的早期密度。 

芬威克树保持了每个查询准确反映当前占用的前缀结构的不变量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        # pair (value, original index)
        arr = [(a[i], i + 1) for i in range(m)]
        arr.sort()

        ft = Fenwick(m)
        ans = 0

        # assign seats in sorted order of values
        for _, pos in arr:
            # inconvenience = number of occupied seats to the left
            ans += ft.sum(pos)
            ft.add(pos, 1)

        print(ans)

if __name__ == "__main__":
    solve()
```该实现在座位索引上构建了一个 Fenwick 树。 每个人都由他们在输入中的原始位置表示，在这种减少中被视为座位索引。 按值排序可确保分配顺序的有效性，并且将每个位置插入芬威克树中会累积之前分配的席位数。 

关键的操作是`ft.sum(pos)`，它计算左侧或当前索引处有多少已占用的座位。 由于我们只添加而不删除，因此该结构清楚地跟踪不断变化的前缀密度。

 ## 边缘情况

 当所有视线值相等时，排序不会强加任何有意义的结构。 该算法纯粹按索引顺序分配座位，并且由于每个新座位总是按排序顺序附加，因此较早的座位不会位于其左侧，从而产生零不便。 

当值按照输入顺序严格递减时，排序会完全颠倒分配顺序。 排序后，每个位置仍按递增的索引顺序插入，因此同样没有较早占用的座位位于新分配的座位的左侧，从而使总数保持为零。 

当值以强制索引交错的方式交替时，芬威克树会正确计算每个插入左侧有多少个早期选择的索引。 每个步骤的贡献与活动前缀的数量相匹配，从而确认数据结构精确地跟踪行的不断变化的拥塞。
