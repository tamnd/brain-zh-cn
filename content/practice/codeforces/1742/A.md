 ## 解决方案
 ## 问题理解

 对于每个测试用例，我们收到三个整数。 任务是确定这三个数字中的任何一个是否可以表示为其他两个数字之和。 

由于只有三个值，因此条件为真有三种可能的方式：

 如果`a + b = c`， 或者`a + c = b`， 或者`b + c = a`。 

限制非常小。 即使测试用例的最大数量也只有 9261 个，每个测试用例只包含 0 到 20 之间的三个整数。这意味着我们可以直接检查每个可能的关系。 总的工作量很小，每个测​​试用例只有一些算术运算。 

当涉及零时，会出现微妙的边缘情况。 

考虑：```
0 0 0
```正确答案是`YES`因为`0 + 0 = 0`。 假设总和必须严格大于加数的粗心解决方案将错误地返回`NO`。 

当所有数字都相等但非零时，会出现另一种边缘情况。```
20 20 20
```正确答案是`NO`。 没有一个数字等于其他两个数字的总和，因为`20 + 20 = 40`。 仅检查两个值是否相等的粗心解决方案可能会错误地返回`YES`。 

另一种情况是在特定位置没有给出最大数字。```
15 7 8
```正确答案是`YES`因为`7 + 8 = 15`。 仅检查的解决方案`a + b == c`会错过这个有效的配置。 

## 方法

 最直接的蛮力想法是测试目标数字的所有可能选择。 由于只有三个数字，我们可以检查第一个数字是否等于其他两个数字之和，第二个数字是否等于其他两个数字之和，第三个数字是否等于其他两个数字之和。 

这种方法是正确的，因为这三项检查完全涵盖了一个数字可能是其余两个数字之和的所有方式。 

对于每个测试用例，我们执行三个添加和三个比较。 即使在最大 9261 个测试用例下，这也只是几万次操作，这是微不足道的。 

关键的观察是问题本身已经只有三种可能的情况。 不需要排序、搜索或任何更复杂的技术。 整个任务简化为直接评估三个有效方程。 

此处的暴力解和最优解实际上是相同的，因为搜索空间是恒定的。

 ## 算法演练

 1.读取测试用例的数量。 
2. 对于每个测试用例，请阅读`a`,`b`， 和`c`。 
3. 检查是否`a + b == c`。 

如果这是真的，则一个数字是其他两个数字的总和，所以答案是`YES`。 
4. 检查是否`a + c == b`。 

这涵盖了第二个数字是总和的情况。 
5. 检查是否`b + c == a`。 

这涵盖了第一个数字是总和的剩余可能性。 
6. 如果三项检查中至少一项为真，则打印`YES`。 否则打印`NO`。 

### 为什么它有效

 三个数字之一只能是三个方程之一中其他两个数字的总和：`a + b = c`,`a + c = b`， 或者`b + c = a`。 

该算法会检查所有三种可能性。 如果存在任何有效关系，则这些比较之一成功并且算法打印`YES`。 如果所有三个比较都失败，则没有数字等于其他两个的总和，因此正确答案是`NO`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    a, b, c = map(int, input().split())

    if a + b == c or a + c == b or b + c == a:
        print("YES")
    else:
        print("NO")
```第一行读取测试用例的数量。 每次迭代读取三个整数。 

里面的情况`if`语句直接实现了算法中讨论的三个方程。 使用逻辑或意味着答案变成`YES`一旦找到任何有效的总和关系。 

除了检查所有三种可能性之外，不存在边界条件问题。 数字非常小，因此 Python 中不可能出现整数溢出。 检查的顺序并不重要，因为每个有效的配置都会被测试。

 ## 边缘情况

 考虑输入：```
1
0 0 0
```该算法评估：`0 + 0 == 0`，这是事实。 

由于其中一项检查成功，因此会打印`YES`。 这可以正确处理所有值都为零的特殊情况。 

考虑输入：```
1
20 20 20
```该算法评估：`20 + 20 == 20`→ 假`20 + 20 == 20`→ 假`20 + 20 == 20`→ 假

 所有检查均失败，因此打印`NO`。 这可以正确处理相等的非零值。 

考虑输入：```
1
15 7 8
```该算法评估：`15 + 7 == 8`→ 假`15 + 8 == 7`→ 假`7 + 8 == 15`→ 正确

 第三个条件成立，所以答案是`YES`。 这说明了为什么只检查一种排序是不正确的。
