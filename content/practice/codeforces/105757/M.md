 ## 解决方案
 ## 问题理解

 给定一个整数数组，我们需要支持涉及该数组各段的“交替求和”的操作。 线段的交替和的计算方法是：将线段的第一个元素带加号，下一个元素带减号，然后再次加，依此类推，从左向右移动时，每一步都会翻转符号。 

核心任务是有效地处理多个查询。 每个查询要么更新数组中的单个位置，要么要求连续子数组的交替和。 对于某个范围内的查询$[l, r]$，结果是值$a_l - a_{l+1} + a_{l+2} - \dots$其符号纯粹由索引距离决定$l$，而不是通过全局数组中的原始奇偶校验。 

输入大小足够大，通过迭代范围重新计算每个查询的总和会太慢。 如果有多达$10^5$元素和$10^5$查询，天真的$O(n)$每个查询方法导致$10^{10}$在最坏的情况下进行操作，这远远超出了典型的时间限制所允许的。 这迫使我们维护一些支持点更新和快速范围聚合的结构。 

当尝试直接重用前缀和时，会出现一个微妙的问题。 交替符号取决于查询的左边界。 例如，考虑数组$[1, 2, 3, 4]$。 的交替和$[1, 3]$是$1 - 2 + 3 = 2$，但是如果我们移动该段，符号模式就会完全改变。 这种对起始索引的依赖使得直接前缀和不够，除非我们对其进行标准化。 

当以影响许多重叠查询的方式更新更改值时，就会出现边缘情况。 例如，如果数组除一个更新位置外全部为零，则简单的重新计算将重复地重新扫描未受影响的区域。 另一个边缘情况是单元素查询，其中答案只是该位置的值，而不管符号规则如何，并且即使在退化范围内错误地应用符号翻转的实现也可能返回错误的结果。 

## 方法

 蛮力方法独立计算每个交替和查询。 对于查询$[l, r]$，我们迭代自$l$到$r$，根据元素的偏移奇偶校验添加和减去元素。 这是直接且正确的，因为它直接遵循定义。 然而，每次查询的成本$O(r - l + 1)$，并且在许多查询中，这会退化为二次行为。 在大量输入的情况下，这会导致数百亿次操作。 

关键的观察结果是交替符号模式是可预测的并且可以被吸收到阵列本身的变换中。 如果我们定义一个新数组$b[i] = a[i]$什么时候$i$是偶数并且$b[i] = -a[i]$什么时候$i$是奇数（或反之亦然，具体取决于索引约定），则前缀和$b$对从固定原点开始的交替行为进行编码。 挑战在于查询从任意位置开始，因此我们需要将符号模式与查询的左端点对齐。 

这种对齐可以通过存储转换后的数组的前缀和并通过奇偶校验进行调整来处理$l$。 一旦这种转换到位，每个范围查询就变成两个前缀和的差，并且可以使用支持点修改的芬威克树或线段树来处理更新。 

自然适合的结构是 Fenwick 树，因为它支持对数时间内的两种操作并保持实现简单。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n)$每个查询|$O(n)$| 太慢了 |
 | 带有符号变换的 Fenwick 树 |$O(\log n)$每个查询|$O(n)$| 已接受 |

 ## 算法演练

 我们在数组的转换版本上维护一棵 Fenwick 树。 

1. 为每个索引定义一个转换后的值$i$: 乘以$a[i]$经过$+1$或者$-1$取决于其位置平价。 这修复了独立于查询的全局交替模式。 此步骤的原因是将移位符号问题转换为静态问题。 
2. 在这个转换后的数组上构建一棵 Fenwick 树。 这使我们能够有效地查询转换值的前缀和。 
3. 处理索引处的更新$i$，我们计算新变换值和旧变换值之间的差异，并在 Fenwick 树中应用点更新。 这确保树始终反映当前的数组状态。 
4. 回答询问$[l, r]$，我们计算前缀和$r$并减去前缀总和$l - 1$，但我们必须纠正查询中交替符号取决于的事实$l$。 如果$l$相对于我们的变换有错误的奇偶性，我们翻转结果符号。 
5. 返回调整后的结果作为答案。 

其起作用的关键原因是转换后的前缀和代表从固定原点开始的交替累积。 任何段都可以表示为两个这样的前缀和的差，唯一的差异是段的起始奇偶校验是否与转换的基本奇偶校验匹配。 

### 为什么它有效

 不变的是，在任何点，芬威克树都存储全局交替版本的数组的前缀和。 在这种固定符号约定下，任何查询范围和都可以分解为两个前缀累加。 唯一的不匹配是由查询开始的相对移位引起的，并且这种不匹配完全由单个奇偶校验校正捕获。 由于更新和查询都保留了转换表示的一致性，因此任何操作序列都不会在树状态和底层数组之间引入不一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    n, q = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    fw = Fenwick(n)

    def val(i):
        return a[i] if i % 2 == 0 else -a[i]

    for i in range(1, n + 1):
        fw.add(i, val(i))

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            i = int(tmp[1])
            x = int(tmp[2])

            old = val(i)
            a[i] = x
            new = val(i)

            fw.add(i, new - old)

        else:
            l, r = int(tmp[1]), int(tmp[2])

            res = fw.sum(r) - fw.sum(l - 1)

            if l % 2 == 1:
                res = res
            else:
                res = -res

            print(res)

if __name__ == "__main__":
    solve()
```Fenwick 树仅负责维护转换后数组的前缀和。 这`val(i)`函数编码全局交替模式。 更新根据先前的转换值计算增量，以便树保持一致。 

查询逻辑依赖于这样一个事实：变换后的空间中的任何范围总和都对应于从索引 1 开始的交替总和。如果实际查询以不同的奇偶校验开始，我们将翻转符号一次。 

一个常见的实现陷阱是忘记更新也必须应用符号转换。 另一种方法是混合基于 0 和基于 1 的索引，这会默默地破坏奇偶校验对齐。 

## 工作示例

 考虑一个数组$[1, 2, 3, 4]$查询要求交替总和$l = 2$到$r = 4$。 

我们维持转变后的价值观$b[i] = (+a[i], -a[i], +a[i], -a[i])$取决于奇偶校验。 

| 步骤| 我| r | 芬威克森(r) | 芬威克森(l-1) | 原始范围 | 奇偶校验修复 | 回答 |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 查询 | 2 | 4 | 计算| 计算| b[2]+b[3]+b[4] | b[2]+b[3]+b[4] | 标志翻转| 决赛|

 原始变换和对应于固定源交替序列，并且奇偶校验校正将其与从索引 2 开始的序列对齐。这表明我们从不重新计算每个查询的符号； 我们只调整单一的全局解释。 

现在考虑单点更新改变$a[3]$。 Fenwick 树仅在索引 3 处更新，其中新旧转换值之间存在差异。 更新前后的查询立即反映了变化，表明动态修改下结构保持了一致性。

 ## 边缘情况

 单元素段，例如$[i, i]$应该总是返回$a[i]$与奇偶校验变换无关。 在此算法中，变换后的数组的 Fenwick 总和给出$+a[i]$或者$-a[i]$，但奇偶校验校正会在需要时取消该效果，恢复原始值。 例如，如果$a = [5]$, 查询$[1,1]$产生 5，因为没有发生范围减法并且符号校正与固定基数对齐。 

另一个边缘情况是重复更新第一个或最后一个元素。 由于每次更新仅影响一个 Fenwick 指数，因此结构保持稳定。 例如，从$[1, 2, 3]$，将索引 1 更新为 10 仅更改位置 1 处存储的增量。后续范围查询会立即反映这一点而无需重新计算，从而确认更新的索引之外不存在隐藏的依赖关系。
