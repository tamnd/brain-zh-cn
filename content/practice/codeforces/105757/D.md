 ## 解决方案
 ## 问题理解

 我们从排序后的数组开始$$[1,2,3,\dots,n].$$三个位置$i<j<k$被选择，与$j-i>1$。 该段$[i,j-1]$是相反的，并且该段$[j,k]$是相反的。 

在最初的交互式版本中，我们可以要求子数组的反转计数。 在黑客版本中，这些值$n,i,j,k$直接作为输入给出，我们必须离线重建相同的逻辑。 

关键的观察是结果数组的形状。 

第一次反转转变$$[i,i+1,\dots,j-1]$$进入$$[j-1,j-2,\dots,i].$$第二次反转转变$$[j,j+1,\dots,k]$$进入$$[k,k-1,\dots,j].$$外面的一切$[i,k]$保持排序。 

里面$[i,k]$，我们得到两个递减块：$$[j-1,\dots,i,\; k,\dots,j].$$由于第一个块中的每个值都小于第二个块中的每个值，因此两个块之间没有反转。 所有反转都来自每个递减块内部。 

让$$a=j-i,
\qquad
b=k-j+1.$$那么每个块贡献的反转计数为$$\frac{a(a-1)}2$$和$$\frac{b(b-1)}2.$$离线版本仅提供$n,i,j,k$，但理解这些反演公式正是原来解法所依赖的。 

约束条件允许$n$最多$10^9$，但最多只有$100$测试用例。 任何$O(1)$或者$O(\log n)$每个测试用例的计算很简单。 模拟长度数组$10^9$不可能，因此解决方案必须是纯数学的。 

一个常见的错误是混淆第一个反向段的长度。 

例如，如果```
i=2, j=5
```那么该段是$[2,4]$，其长度为$$j-i=3,$$不是$j-i+1$。 

另一个容易出现的差一错误出现在第二段中。 它的长度是$$k-j+1.$$为了```
j=4, k=6
```该段是$[4,6]$，其中包含三个元素。 

使用$k-j$相反会低估反转。 

## 方法

 暴力方法将显式构建数组，执行两次反转，然后计算反转次数。 天真地计算反转需要检查每一对，从而导致$O(n^2)$工作。 

当以下情况时，该方法立即失败$n$可以达到$10^9$。 连构建阵法都是不可能的。 

两次反转创建的结构比最终数组本身包含更多信息。 

生成的排列由三部分组成：$$\text{sorted prefix}$$其次是$$\text{first decreasing block}$$其次是$$\text{second decreasing block}$$其次是$$\text{sorted suffix}.$$在长度递减的块内$L$，每对位置都形成一个反转。 反转次数恰好是$$\binom{L}{2}
=
\frac{L(L-1)}2.$$由于第一个块中的每个值都小于第二个块中的每个值，因此永远不会发生跨块反转。 

这将问题转换为关于线段长度的简单算术，而不是操纵排列本身。

 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 数学分析| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读$n,i,j,k$。 
2. 计算第一个反转线段的长度：$$a=j-i.$$该段是$[i,j-1]$，所以它的长度不是$j-i+1$。 

1. 计算第二个反向线段的长度：$$b=k-j+1.$$该段是$[j,k]$，包括两端。 

1. 计算第一个块贡献的反转计数：$$inv_1=\frac{a(a-1)}2.$$长度递减序列$a$包含每对位置的反转。 

1. 计算第二个块贡献的反转计数：$$inv_2=\frac{b(b-1)}2.$$1. 输出$$inv_1+inv_2.$$### 为什么它有效

 两次反转后的间隔$[i,k]$变成两个独立的递减块。 每个反转都完全位于其中一个块内。 

第一个块的贡献正好$\binom{a}{2}$反转，第二个贡献完全$\binom{b}{2}$。 

块之间不存在反转，因为源自第一个块的每个值都小于源自第二个块的每个值。 由于所有剩余位置都保持排序，因此不存在额外的反转。 

两个三角形数之和正是总的反转计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n, i, j, k = map(int, input().split())
        
        a = j - i
        b = k - j + 1
        
        ans = a * (a - 1) // 2 + b * (b - 1) // 2
        print(ans)

solve()
```实现完全是算术。 

第一段是$[i,j-1]$，所以它的长度是`j - i`。 这是最容易犯差点错误的地方。 

第二段是$[j,k]$，所以它的长度是`k - j + 1`。 

两个反转计数都是三角数。 Python 整数可以轻松处理最大可能的值，因为$n\le 10^9$，最多给出关于$5\times10^{17}$，完全在 Python 的整数范围内。

 ## 边缘情况

 考虑最小的有效配置：```
1
4 1 3 4
```第一段是`[1,2]`， 长度`2`，贡献一个反转。 第二段是`[3,4]`， 长度`2`，贡献一个反转。 反转后数组变为：$$[2,1,4,3].$$反转计数为$1+1=2$。 该公式计算出完全相同的值。 

现在考虑第二个块非常短的情况：```
1
10 3 7 8
```这里$$a=4,\qquad b=2.$$答案是$$\binom{4}{2}+\binom{2}{2}
=
6+1
=
7.$$使用$k-j$而不是$k-j+1$会错误地设置$b=1$并失去一个反转。 这正是第二段中的包容性终点很重要的原因。 

最后，考虑一个巨大的价值：```
1
1000000000 1 500000000 1000000000
```该算法仅执行少量整数运算，并且从不分配大小的数组$10^9$。 复杂度保持不变，这是给定范围内唯一可行的方法。
