 ## 解决方案
 ## 问题理解

 我们有一条街道$2n$连续的房子，每栋房子只出售一层特定尺寸的蛋糕$1$和$n$。 每个尺寸恰好出现两次。 

两个人从家里开始$1$。 他们每个人都想独立地构建一个由层组成的完整蛋糕$1$通过$n$，并且他们必须按尺寸递增的顺序购买层。 由于每一层都必须从特定的房屋中挑选，因此他们沿着街道步行以按顺序收集所需的房屋。 

任务是决定如何在两个人之间分配每个大小的两个可用事件，以及他们访问它们的顺序，以便使两个人的总步行距离最小化。 

关键输出是两个人行走距离的最小总和。 

约束条件$n \le 10^5$意味着输入大小可达$2 \cdot 10^5$。 任何具有二次行为的解，甚至$O(n^2)$，太慢了，因为它涉及到$10^{10}$运营。 通常需要线性或近线性策略$O(n \log n)$或者$O(n)$。 

当人们试图贪婪地独立分配每个值最近出现的位置时，就会出现一个微妙的陷阱。 这会失败，因为早期层的选择限制了未来的可用性，并且可能会迫使回溯距离变大。 

例如，考虑以下情况：取最近出现的大小$1$块大小的两个不错的选择$2$，迫使进行长时间的向后旅行。 天真的贪婪方法不会预见到这种相互作用。 

## 方法

 暴力策略将尝试模拟所有可能的方式，将每种大小的两个事件分配给 Sasha 或 Dima，同时决定两者的移动顺序。 这本质上探索了一个分支过程，其中每个尺寸$i$，我们选择两个位置中的哪一个分配给哪个人。 由于每种尺寸都有两种选择，并且有$n$尺寸，有$2^n$作业，对于每个作业，我们仍然会模拟步行成本。 即使进行修剪，这也是指数级的并且变得不可能超过小值$n$。 

关键的结构见解是，运动仅取决于线上的位置，并且下一个所需的层总是大于前一层。 这意味着每个人的路径在大小顺序上是单调的，但在位置上不一定是单调的。 

我们可以考虑将位置数组分成两个递增的索引子序列，每个人一个，而不是分配大小。 每个人将以大小递增的顺序访问其分配的位置，并且成本只是从位置开始的连续访问索引之间的绝对差之和$1$。 

现在关键的简化：对于每个尺寸$i$，我们正好有两个位置$p_i$和$q_i$。 其中一份交给萨莎，另一份交给迪玛。 我们希望决定此分配，以使总行驶距离最小化。 

一个重要的观察结果是，对于每种尺寸，两个人中恰好有一个人将“吸收”该值的转变，并且如果我们保持每个人访问的最后位置，则可以增量计算成本贡献。 

这导致了一个贪婪的动态过程：我们处理尺寸$1$到$n$，对于每个尺寸，我们决定哪个人采取哪种方式，以最小化添加到他们当前位置的直接移动成本。 由于每一步仅取决于两个人的最后位置，因此局部贪婪选择就足够了。 

我们总是将两个可用位置中较接近的位置分配给移动成本较小的人，并相应地更新他们当前的位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n)$|$O(n)$| 太慢了 |
 | 最优贪心跟踪最后位置 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们首先预处理每个层大小的位置，以便我们知道每个值出现的两个索引。 

1. 存储每个值$i$它在数组中的两个位置。 这允许恒定时间访问候选动作。 
2. 维护代表Sasha和Dima当前位置的两个指针。 两者都从索引开始$1$，因为它们从第一个房子开始。 
3. 过程值来自$1$到$n$以递增的顺序，因为两个人都必须以递增的大小收集层，因此未来的决定不会影响过去的可用性。 
4. 对于每个值$i$，我们有两个位置。 我们以两种可能的方式考虑将一个职位分配给 Sasha 而另一个职位分配给 Dima 的成本：

 第一次配对$(p_i \to S, q_i \to D)$，和第二对$(p_i \to D, q_i \to S)$。 
5. 使用两个人的当前位置计算每个配对的增量成本。 选择总移动成本较小的任务。 
6. 更新两个当前职位以反映所选的任务并添加成本。 

我们评估这两项分配的原因是，决策不是每个人的本地决策，而是联合决策：交换端点可以显着减少未来的旅行。 

### 为什么它有效

 在任何一步，两个人都固定了“最后访问的位置”，未来的移动仅取决于这两个状态。 由于每个值必须由每个人恰好收集一次，因此唯一的自由度是我们如何分割这两个事件。 

该算法是最优的，因为在每一层，它都会选择最小化立即移动成本总和的分割，并且未来的层不依赖于_哪个人获得了超出其结果位置的特定事件_。 因此，系统具有最佳子结构：可以通过在每一层做出最佳局部配对决策来构建最佳全局分配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    pos = [[] for _ in range(n + 1)]
    for i, v in enumerate(arr, 1):
        pos[v].append(i)

    # starting positions
    s = 1
    d = 1
    ans = 0

    for i in range(1, n + 1):
        a, b = pos[i]

        # option 1: a->S, b->D
        cost1 = abs(s - a) + abs(d - b)

        # option 2: a->D, b->S
        cost2 = abs(s - b) + abs(d - a)

        if cost1 <= cost2:
            ans += cost1
            s, d = a, b
        else:
            ans += cost2
            s, d = b, a

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先对每个层的位置进行分组，以便可以在恒定时间内访问每个值。 变量`s`和`d`分别代表 Sasha 和 Dima 最近访问的房屋指数。 在每一层，我们评估其两次出现的可能分配，并计算当前位置的移动成本。 交换决策确保两个端点始终分配在更便宜的配置中。 

一个微妙的点是，我们在每次决定后同时更新两个位置。 这是至关重要的，因为未来的运动取决于两国共同。 仅更新一个就会破坏正确性。

 ## 边缘情况

 关键的边缘情况是值的两次出现相邻。 例如，对于值$i$, 职位$(k, k+1)$，选择错误的分配仍然具有类似的直接成本，但会影响未来的可达性。 该算法自然地处理这个问题，因为两个配对选项都是对称评估的，并且当前状态始终一致更新。 

另一个重要的情况是当发生的事件相距最大时，例如$1$和$2n$。 在这里，贪婪分配可能看起来违反直觉，但由于两个人总是按值顺序向前移动，贪婪分配端点仍然会产生最佳分割。 状态更新可确保立即考虑长跳转，从而防止以后隐藏的成本累积。
