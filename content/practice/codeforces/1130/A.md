 ## 解决方案
 ## 问题理解

 我们得到一个包含正数、负数和可能的零的数组。 我们需要选择一个非零整数$d$这样每个元素除以之后$d$，至少有一半的数组元素是正数。 更准确地说，除法后的正值的数量必须至少为$\lceil n/2 \rceil$。 

除法后的实际大小并不重要。 只有标志才重要。 诸如以下的值$2.5$仍为正值，同时$0$既不积极也不消极。 

限制非常小。 该数组最多包含 100 个元素，每个值都位于$-1000$和$1000$。 由于只有 100 个数字，即使对数组进行强力检查也是微不足道的。 

关键的观察来自于分裂如何影响星座。 除以正数会使每个符号保持不变。 除以负数会将每个正数翻转为负数，将每个负数翻转为正数。 在任何一种情况下，零都保持为零。 

一些边缘情况很容易导致错误。 

考虑：```
3
0 0 5
```如果我们除以正数，数组符号保持不变$(0,0,+)$，因此只有一个正值。 自从$\lceil 3/2 \rceil = 2$，这还不够。 忽略零的粗心解决方案可能会错误地得出正数占多数的结论。 

考虑：```
5
-1 -2 -3 0 0
```使用负除数将三个负数翻转为正数，得到三个正值。 正确答案是$-1$。 仅检查正除数的解决方案会错误地打印 0。 

考虑：```
4
1 -1 0 0
```有一种积极的一面，也有一种消极的一面。 正除数产生一个正数。 负除数也会产生一个正数。 我们至少需要两个正数，所以正确答案是 0。 

许多零的存在是主要的微妙之处，因为无论除数如何，零永远不会变成正数。 

## 方法

 暴力方法会尝试每个有效的除数$-1000$到$1000$，不包括零。 对于每个除数，我们将除以每个数组元素并计算有多少结果为正。 

这是有效的，因为搜索空间很小。 可能的约数只有 2000 个，数组元素最多有 100 个。 最坏情况的工作大约是$2000 \times 100 = 200{,}000$操作，很容易符合限制。 

有趣的是，注意到除数的确切值是无关紧要的。 只有它的符号才重要。 

如果$d > 0$，每个积极的元素保持积极，每个消极的元素保持消极。 

如果$d < 0$，每个正元素都变成负元素，每个负元素都变成正元素。 

这意味着只有两种不同的情况需要检查：

 首先，使用正除数。 正值的数量等于原始数组中正元素的数量。 

其次，使用负除数。 正值的数量等于原始数组中负元素的数量。 

让：

-$pos$是正元素的数量。 
-$neg$是负元素的数量。 
-$need = \lceil n/2 \rceil$。 

如果$pos \ge need$，我们可以打印任何正除数，例如 1。 

否则，如果$neg \ge need$，我们可以打印任何负除数，例如-1。 

否则，两个符号选择都无法产生足够的正值，因此我们打印 0。

 | ---| ---| ---| ---|
 | 蛮力 | O(2000·n) | O(1) | O(1) | 已接受 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取数组并统计有多少个元素为正数。 将此计数存储在`pos`。 
2. 计算有多少个元素为负数。 将此计数存储在`neg`。 
3. 计算所需的正值数量：$$need = \left\lceil \frac{n}{2} \right\rceil$$在整数算术中，这是`(n + 1) // 2`。 
4. 如果`pos >= need`， 打印`1`。 

正除数保留所有符号，因此除法后正值的个数正好是`pos`。 
5. 否则，如果`neg >= need`， 打印`-1`。 

负除数会翻转符号，因此每个负元素都会变成正元素。 正值的数量恰好变成`neg`。 
6. 否则打印`0`。 

两种符号选择都不能产生足够的正值。 

### 为什么它有效

 每个非零商的符号仅取决于被除数的符号和除数的符号。 除数的大小永远不会影响结果是否为正。 

使用正除数保留原始符号分布，准确产生`pos`积极的价值观。 使用负除数交换正数和负数，从而精确产生`neg`积极的价值观。 由于这是仅有的两种可能的结果，因此检查任一计数是否达到$\lceil n/2 \rceil$完全表征了所有有效答案。 如果两个计数都不够大，则没有除数可以满足要求。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

pos = sum(1 for x in a if x > 0)
neg = sum(1 for x in a if x < 0)

need = (n + 1) // 2

if pos >= need:
    print(1)
elif neg >= need:
    print(-1)
else:
    print(0)
```第一部分分别统计正负元素。 零被忽略，因为它们对除法后的正值数量没有贡献。 

变量`need`商店$\lceil n/2 \rceil$。 使用`(n + 1) // 2`正确处理偶数和奇数`n`。 

检查顺序仅在两个计数都满足要求时选择打印哪个有效答案才重要。 该问题允许任何有效除数，因此打印`1`首先是完全可以接受的。 

不执行实际的划分。 该解决方案完全依赖于符号行为，这是关键的简化。

# helper: run solution on input string, return output string
import sys
import io

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pos = sum(1 for x in a if x > 0)
    neg = sum(1 for x in a if x < 0)

    need = (n + 1) // 2

    if pos >= need:
        print(1)
    elif neg >= need:
        print(-1)
    else:
        print(0)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    result = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return result

# sample-style case
assert run("5\n10 0 -7 2 6\n") == "1"

# minimum size, positive
assert run("1\n5\n") == "1"

# minimum size, negative
assert run("1\n-5\n") == "-1"

# impossible because zeros dominate
assert run("4\n1 -1 0 0\n") == "0"

# all negatives
assert run("5\n-1 -2 -3 -4 -5\n") == "-1"

# all positives
assert run("6\n1 1 1 1 1 1\n") == "1"

# boundary count exactly equal to need

 ## 边缘情况

 考虑：```
4
1 -1 0 0
```我们有：```
pos = 1
neg = 1
need = 2
```正除数产生一个正值。 负除数也会产生一个正值。 两者都没有达到 2，因此算法打印：```
0
```这可以正确处理零占据数组过多位置的数组。 

考虑：```
5
-1 -2 -3 0 0
```计数是：```
pos = 0
neg = 3
need = 3
```自从`neg`达到阈值，算法打印`-1`。 除以负数会将所有三个负数变为正数，满足要求。 

考虑：```
3
0 0 5
```计数是：```
pos = 1
neg = 0
need = 2
```两个计数都没有达到阈值，因此算法打印：```
0
```这证实了无论选择什么除数，零永远不会帮助增加正值的数量。
