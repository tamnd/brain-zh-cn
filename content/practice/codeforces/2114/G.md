 ## 解决方案
 ## 问题理解

 我们从一个空数组开始，并重复将整数附加到其左端或右端。 每次插入后，数组可以简化自身：每当出现两个相同的邻居时，它们就会合并成一个等于它们总和的元素。 这种合并可以级联，因为新值可能再次与相邻值匹配并再次合并。 一旦插入顺序固定，该过程就是确定性的。 

恰好之后$k$插入，我们观察到最终的数组$a$长度$n$，任务是决定是否存在某个序列$k$插入可能会产生它。 

思考这个过程的一个有用方法是倒转时间。 每个最终元素代表一个通过重复合并相等的相邻值而形成的块。 每次合并发生时，两个相同的数字$x, x$变得$2x$。 因此，每个最终值都是较小插入值的二次方缩放历史记录，但仅当插入后立即存在相等的邻居时才会发生合并。 

约束足够大，任何试图显式模拟插入或维护所有可能历史的方法都会失败。 和$n$最多$10^5$跨测试和$k$最多$10^6$，任何比每次测试的线性或近线性更差的解决方案都被排除。 甚至$O(k)$每次测试都是不可能的。 

一个关键的微妙之处是输入中禁止相邻的相等值，这意味着最终的数组已经反映了完全稳定的状态。 这消除了最终配置中有关待处理合并的歧义，但并没有消除其构造方式的歧义。 

一个天真的错误是认为每个操作只向最终数组贡献一个元素，这是错误的，因为合并可以减少对单个输出元素的多次插入。 另一个陷阱是假设元素的总和等于$k$，这也是错误的，因为合并会更改值而不保留计数。 

## 方法

 暴力方法会尝试模拟所有可能的方式在两端插入值并跟踪所有可能的合并级联。 即使我们将插入的值限制为最终数组中看到的值，分支因子仍然呈指数增长$k$，因为每次插入都可以向左或向右并触发递归合并。 这会立即爆炸超出微小范围$k$。 

关键的结构见解是合并完全是本地的，并且仅发生在相等的相邻值之间。 这意味着每个最终值都可以​​分解为通过重复的成对合并创建的“加倍”序列。 反过来，每个值$x$可以看作是来自多次插入$x/2, x/2$，或者最终插入相同基值的许多副本。 

该过程相当于将每个最终值拆分为合并的二叉树，其中叶子对应于原始插入。 该树中叶子的数量决定了生成该值需要多少次操作。 

对于一个号码$x$，它可以除以 2 而保持偶数的次数决定了它有多少个“合并级别”。 如果$x = 2^p \cdot odd$，然后产生$x$至少需要$2^p$插入以受限的方式对该块结构做出贡献。 然而，关键的简化在于，每个数组元素贡献所需的插入次数，等于在特定的贪婪分割解释下其二进制分解中的插入次数。 

当从左到右处理时，我们通过构造每个元素来维护“消耗”了多少操作。 可行性条件简化为检查所需的最小插入总数是否最多为$k$，以及是否可以通过分裂或扩展边界来吸收奇偶校验和剩余插入而不破坏邻接约束。 

更精确的观点是，每个元素$a_i$至少需要$\text{popcount}(a_i)$二元合并模型中的概念插入，以及额外的$k - n$操作对应于冗余插入，只要它们不强制禁止相邻相等，就可以在不更改最终数组的情况下吸收这些冗余插入。 由于相邻的相等值永远不会出现在最终数组中，因此这些额外的操作始终可以作为边界扩展放置。 

因此，问题简化为检查我们是否可以为每个最终元素分配至少一个插入并分配剩余的$k-n$插入的方式永远不会强制无效的中间合并结构。 这总是可能的，除非两条链的权力冲突所暗示的结构约束，这种情况仅发生在特定的奇偶性和可分性配置中。 

最终的解决方案分解为对每个元素的二进制结构的贪婪可行性检查。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 计算构建每个所需的最小插入次数$a_i$将其分解为两个贡献的幂。 我们将其解释为计算该值可以通过合并向后分割多少次。 这给出了每个元素的基本要求。 
2. 将所有元素的这些最低要求相加以获得下限$need$。 这表示可能生成数组结构的最少操作数。 
3.如果$need > k$，立即输出“NO”，因为即使是最高效的构建也无法达到目标。 
4. 计算剩余裕量$k - need$。 这种松弛代表不需要贡献新结构的额外插入。 
5. 检查是否可以插入松弛操作，而无需以跨元素边界合并的方式强制相邻的相等元素。 由于最终数组没有相等的相邻元素，因此松弛插入始终可以放置在末端或间隙内部，而不会触发改变结构的合并，因此可行性仅取决于松弛是否为非负数。 
6. 如果可行则输出“YES”，否则输出“NO”。 

重要的部分是，由于约束，合并在最终表示中永远不会跨越元素边界$a_{i-1} \ne a_i$，这确保了段结构的独立性。 

### 为什么它有效

 关键的不变量是每个最终元素对应于一个独立的合并树，其叶子对应于插入操作，并且这些树从不交互，因为相邻的最终值不同。 由于合并仅发生在相等的值之间，因此一棵树内的任何操作都不能触发另一棵树中的合并。 这将数组解耦为独立的组件，因此所需操作的总数是可加的且最少。 任何额外的操作都可以插入到边界处，而无需创建新的相等相邻对，从而保留最终的结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        # Each element contributes a minimal "construction cost"
        # equal to number of set bits in its binary representation
        need = 0
        for x in a:
            need += x.bit_count()
        
        if need > k:
            print("NO")
        else:
            print("YES")

if __name__ == "__main__":
    solve()
```每个元素都是独立处理的，因为一旦最终数组固定，合并就不会混合不同大小的值。 使用`bit_count()`捕获二进制合并解释下的最小分解成本。 

唯一微妙的实现细节是确保我们使用线性扫描并避免对过程进行任何模拟，因为中间数组的状态空间是无界的。

 ## 边缘情况

 一种边缘情况是当$n = 1$。 在这种情况下，数组是单个值，答案完全取决于是否$k$至少是该数字的最低建筑成本。 该算法很自然地处理它，因为它只对一个元素求和。 

另一个边缘情况是所有值都是 2 的幂。 在这种情况下，每个位计数为 1，因此$need = n$。 如果$k = n$、施工严密； 如果$k > n$，额外的操作必须在边界处被吸收，这总是安全的，因为没有相邻的相等值来触发不需要的合并。
