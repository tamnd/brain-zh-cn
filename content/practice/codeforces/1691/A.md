 ## 解决方案
 ## 问题理解

 给定一个整数序列，我们需要删除尽可能少的数字，以便剩余序列中的每对连续数字之和为偶数。 如果两个数字都是偶数或都是奇数，则两个数字的和为偶数。 因此，该条件转化为要求剩余序列必须由连续位置上的所有偶数或所有奇数组成。 我们不受数字原始顺序的限制，但我们必须保留我们所保留的顺序； 我们无法对元素重新排序。 

输入由多个测试用例组成。 每个测试用例提供序列的长度和序列本身。 所有测试用例的元素总数不超过 100,000。 这个界限意味着任何比序列长度的线性复杂度更差的解决方案都可能太慢。 具有 O(n^2) 行为的算法在最坏的情况下将执行大约 100 亿次操作，因此被排除在外。 线性或线性算术方法是可行的。 

一个微妙的边缘情况是当序列已经有效时，例如`[3, 5, 9, 7]`。 这里，不需要删除，因为连续的对都是偶数。 另一个棘手的情况是当序列交替奇偶校验时，例如`[2, 3, 4, 5]`。 仅查看第一次违规的简单方法可能会删除错误的元素，并且需要删除不必要的内容。 正确的方法需要了解奇数和偶数的总数以确定最小移除量。 

## 方法

 暴力方法将迭代序列，并在连续对的总和为奇数时尝试贪婪地删除元素。 我们可以尝试删除违规对的第一个或第二个元素，并递归地继续检查序列。 这种方法之所以有效，是因为删除一个数字会破坏违规行为，但它很快就会变得低效。 每次删除都可能导致递归调用，该调用检查几乎整个剩余序列，从而产生 O(n^2) 的最坏情况复杂度。 对于 n 高达 100,000 的情况，这太慢了。 

关键的见解是，只有当两个数字具有相同的奇偶校验时，连续对的总和才能为偶数。 这意味着最终序列必须包含具有相同奇偶校验的数字。 因此，最优解就是决定是保留所有偶数还是所有奇数。 最小移除次数是偶数和奇数的计数中较小的一个。 我们不需要模拟删除单个元素或检查每对元素，因为奇偶校验与位置无关。 这一观察结果将问题简化为线性扫描来计算奇偶校验，从而为每个测试用例提供 O(n) 时间。

 ## 算法演练

 1.读取测试用例的数量。 每个测试用例将被独立处理。 
2. 对于每个测试用例，读取序列长度和序列本身。 
3. 初始化两个计数器：一个用于偶数，一个用于奇数。 
4. 迭代序列。 对于每个元素，如果可被 2 整除，则递增偶数计数器，否则递增奇数计数器。 
5. 计算偶数个数和奇数个数之间的最小值。 这是所需的最小删除次数，因为保留较大的组可以保留最大数量的元素，同时满足连续总和条件。 
6. 打印测试用例的最小数量。 

为什么有效：在计算所有数字的奇偶校验后，我们确切地知道必须删除多少元素才能使所有剩余的数字共享相同的奇偶校验。 这保证了每个连续的对的总和将为偶数。 没有其他配置可以产生更少的移除，因为奇数和偶数的任何混合都不可避免地产生至少与较小组的大小一样多的违规。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    even_count = sum(1 for x in a if x % 2 == 0)
    odd_count = n - even_count
    print(min(even_count, odd_count))
```该代码使用快速 I/O 有效地读取所有输入。 它一次性计算偶数和奇数的数量，然后打印两次计数中的最小值。 使用`n - even_count`计算奇数计数避免了第二次循环，使代码更干净且速度稍快。 边缘情况是自然处理的：如果所有数字都是偶数，`odd_count`为零，因此最小值为零，正确地表明不需要移除。

 ## 边缘情况

 如果序列的所有元素具有相同的奇偶校验，则算法正确输出 0。例如，`[2,4,6]`结果`even_count=3`,`odd_count=0`,`min(even_count, odd_count)=0`。 如果序列交替奇偶校验，例如`[2,3,4,5]`，计数为`even_count=2`,`odd_count=2`，产生最小去除量 2。这确保算法永远不会低估去除量。 单元素序列的处理自然：`even_count`或者`odd_count`一个为 1，另一个为 0，因此最小值为 0。该解决方案对于所有有效输入都是稳健的。
