 ## 解决方案
 ## 问题理解

 我们被要求确定，对于给定的整数数组，任何连续子数组中的最大值是否至少与该子数组的总和一样大。 简单来说，对于数组的每个可能的段，单个最大数字不得小于该段中所有数字的总和。 如果存在一个子数组且其总和超过最大元素，则答案为“NO”； 否则，为“YES”。 

输入提供多个测试用例，每个测试用例都有一个长度最多为 200,000 的数组，所有测试用例的元素总数上限为 200,000。 每个元素的范围可以是 -10^9 到 10^9。 考虑到 n 最大可达 2·10^5 并且时间限制为 2 秒，每个测试用例的复杂度低于 O(n) 的算法可能太慢。 这排除了任何尝试显式检查所有子数组的方法，因为这将需要每个数组进行 O(n²) 次操作，在最坏的情况下可能达到 4·10^10。 

当数组包含大量正数且两侧有负数时，就会出现不明显的边缘情况。 例如，在数组 [-1, 5, -1] 中，每个子数组的总和最多为 5，最大元素为 5。如果不考虑长度为 2 或 3 的子数组，或者只查看相邻的总和而不考虑减少总和的负数，那么简单的方法可能会失败。 另一个边缘情况是严格递增的正数序列，例如 [1, 2, 3]，其中前两个元素的总和为 3，等于该子数组中的最大值，但添加下一个元素会产生比迄今为止最大元素大的总和，从而违反了条件。 

## 方法

 暴力方法将检查所有可能的子数组，计算它们的总和和最大值，并验证每个子数组的条件。 对于大小为 n 的数组，大约有 n(n+1)/2 个子数组，独立计算每个总和或最大值将花费 O(n) 时间，总复杂度为 O(n³)。 即使使用数据结构的前缀和和段最大值，仅子数组的数量就使得这种方法在 n = 2·10^5 时不可行。 

关键的观察是，如果条件失败，则它必须在总和在某种意义上局部最大的子数组上失败。 由于任何负元素只会减少总和，因此最危险的子数组是从第一个元素开始或到最后一个元素结束的连续段。 换句话说，我们只需要检查所有真子数组（不包括整个数组）的前缀和和后缀和。 如果每个真前缀和后缀的总和不超过该子数组中任何位置的最大元素，则条件成立。 

这将问题简化为有效计算最大前缀和和最大后缀和并将它们与相邻元素进行比较。 实际上，只需迭代数组并检查真子数组的任何前缀或后缀之和是否严格大于整个数组中的最大值就足够了。 如果存在这样的子数组，则答案为“NO”； 否则，为“YES”。 这种方法每个测试用例的复杂度为 O(n)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 对于每个测试用例，读取数组并确定其最大元素。 这是满足不等式的候选者，因为任何总和都不得超过该最大值。 
2. 检查数组中所有正确的前缀。 将运行总和初始化为零。 从第一个元素迭代到倒数第二个元素，将每个元素添加到运行总和中。 如果在任何时候运行总和超过数组的最大值，则违反条件，因此立即返回“NO”。 
3. 检查数组的所有正确后缀。 将运行总和重置为零，并从最后一个元素迭代到第二个元素，将每个元素添加到运行总和中。 同样，如果总和超过最大元素，则返回“NO”。 
4. 如果两次检查都完成而没有找到违规子数组，则该条件适用于该数组，因此返回“YES”。 

直觉是，不等式仅对于作为数组某些部分的前缀或后缀的子数组是严格的。 任何完全包含在内部的子数组都可以分解为前缀和后缀，并且由于负数只会减少总和，因此如果条件适用于所有前缀和后缀，则它也适用于所有子数组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        max_val = max(a)

        # check prefixes
        prefix_sum = 0
        valid = True
        for i in range(n - 1):
            prefix_sum += a[i]
            if prefix_sum > max_val:
                valid = False
                break

        # check suffixes
        if valid:
            suffix_sum = 0
            for i in range(n - 1, 0, -1):
                suffix_sum += a[i]
                if suffix_sum > max_val:
                    valid = False
                    break

        print("YES" if valid else "NO")

if __name__ == "__main__":
    solve()
```该代码首先识别最大元素。 然后它检查从第一个元素到倒数第二个元素的前缀和，因为包括最后一个元素是不必要的——如果整个数组和超过最大值，数组本身就会违反条件，这是被禁止的。 同样，后缀检查从最后一个元素运行到第二个元素。 如果违反条件，每个循环都会立即中断，从而优化速度。 

## 工作示例

 **示例 1：[-1, 1, -1, 2]**

 | 步骤| 前缀/后缀 | 运行总和 | 最大| 有效的？ |
 | --- | --- | --- | --- | --- |
 | 前缀| -1 | -1 | 2 | 是 |
 | 前缀| -1+1=0 | -1+1=0 0 | 2 | 是 |
 | 前缀| 0-1=-1 | -1 | 2 | 是 |
 | 后缀 | 2 | 2 | 2 | 是 |
 | 后缀 | 2-1=1 | 2-1=1 1 | 2 | 是 |
 | 后缀 | 1+1=2 | 2 | 2 | 是 |

 所有总和≤最大元素，输出YES。 

**示例 2：[2, 3, -1]**

 | 步骤| 前缀| 运行总和 | 最大| 有效的？ |
 | --- | --- | --- | --- | --- |
 | 前缀| 2 | 2 | 3 | 是 |
 | 前缀| 2+3=5 | 5 | 3 | 否 |

 前缀和5超过最大3，输出NO。 

这表明该算法可以正确检测从数组开头开始的子数组中的违规情况。

 ## 边缘情况

 对于像 [100] 这样的单元素数组，算法计算的最大值为 100。由于 n-1 为零，因此会跳过前缀和后缀循环，因此条件自动通过，输出 YES。 

对于全部为负数的数组，例如 [-5, -3, -2]，前缀和从负数开始，并且永远不会超过最大值 -2。 后缀总和同样保持低于-2。 该算法正确返回 YES。
