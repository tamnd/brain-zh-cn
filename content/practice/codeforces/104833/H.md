 ## 解决方案
 ## 问题理解

 我们得到两个由小写字母组成的字符串。 唯一允许的操作采用任何连续的四个字符块并删除其中间的两个字符，从而有效地将长度为四的模式转换为长度为二的模式，同时保留第一个和最后一个字符。 

问题是我们是否可以从源字符串开始，在任何有效的长度为 4 的子字符串位置上应用此操作任意次后，将其精确地转换为目标字符串。 

关键点是该操作会删除字符，但不会对剩余的字符进行重新排序。 它还始终保留每个选定窗口的第一个和最后一个字符，这意味着幸存的字符必须始终源自某些位置，这些位置可以通过永远不在选定窗口的中间来“保护”。 

这些约束允许字符串长度最大为 100000，最多可包含 100000 个测试用例，但总输入大小限制为 200000。这意味着任何解决方案在总输入上都必须基本上是线性的。 每个测试用例甚至每个字符串的任何二次方都会立即失败。 

幼稚的解释会尝试所有删除序列，或者在所有可能的窗口上贪婪地模拟操作。 这会以组合方式爆炸，因为每个操作都会更改字符串长度并创建新的可能窗口。 

当字符在原始字符串中相邻但由于强制删除而无法在最终字符串中保持相邻时，就会出现一种微妙的边缘情况。 例如，如果一个字符始终位于某个长度为 4 的窗口的中间，则可能无法保留它。 仅检查子序列匹配的粗心方法会错误地接受无法保护所需字符免遭删除的情况。 

## 方法

 该操作始终适用于长度为四的窗口，删除内部的两个字符。 如果我们反复观察它的作用，一个有用的思考方式是，只有当角色从未被选为任何应用操作的两个中间位置之一时，角色才能生存。 

我们不是模拟删除，而是翻转视角：原始字符串中哪些字符可以保留下来？ 

暴力方法会尝试所有可能的操作序列。 每个操作可以应用于 O(n) 个位置，并且可以有 O(n) 个操作，从而导致指数或至少 O(n²) 或更差的状态空间。 甚至存储中间字符串也变得不可能。 

关键的见解是该操作在本地保留了奇偶校验结构。 长度为 4 的窗口会删除位置 2 和 3，因此有效地，本地区域内偶数偏移处的字符更有可能存活下来。 如果我们对位置进行索引，则每个操作都会删除两个内部位置，而其余结构的行为就像一个约束匹配问题。 

如果我们看看什么是不可能的，就会出现更直接的重新表述：太“密集”的字符不可能全部保留。 每个操作都会将长度减少 2，因此如果我们执行 k 个操作，长度就会减少 2k。 这已经暗示了 |s| 之间的奇偶校验约束 和|t|。 

更重要的是，考虑从左到右扫描。 每当我们决定保留 s 中的一个字符作为 t 的一部分时，我们必须确保存在一种方法来“路由”它周围的删除，这样它就永远不会成为所选长度为 4 的窗口的中间。 事实证明，这相当于检查我们是否可以贪婪地匹配 s 内的 t，同时遵守间距约束，该间距强制在源中保留的字符之间至少删除两次。 

这导致了贪婪匹配策略：我们尝试将 t 嵌入到 s 中，但确保 s 中选定的索引不会太接近，从而迫使它们进入相同的删除窗口结构。

一个更简单的基于不变式的视图进一步简化：每个操作将四个块减少为两个，这意味着我们实际上是在选择 s 的子序列，并且约束条件是任何两个选定的字符都不能来自被重叠 4 窗口“完全消耗”的片段。 在强制我们从不以冲突的方式从每个长度为 4 的滑动结构中选取多个字符之后，这简化为检查 t 是否可以形成为 s 的子序列。 

最终可行的表征是带有附加约束的贪婪子序列匹配，该附加约束确保删除操作下的间距兼容性。 实际上，这减少了扫描 s 并匹配 t，同时保持所选索引始终在连续选取之间留下至少一个未选择的字符。

 ## 算法演练

 我们将问题视为检查是否可以从 s 中挑选字符来形成 t，同时尊重操作引起的结构限制。 

1. 从两个指针开始，一个代表 s，一个代表 t。 我们尝试将 t 按顺序匹配为 s 的子序列。 这是必要的，因为该操作永远不会改变幸存字符的相对顺序。 
2. 从左向右移动 s。 当s[i]与当前字符t[j]匹配时，我们考虑将其作为最终结果的一部分。 然而，我们不能总是立即安全地获取它，因为我们必须确保它不违反“4窗口删除约束”，这将迫使它稍后进入可移动的中间位置。 
3. 强制执行间隔规则：在 s 中任意两个选定的索引之间，必须至少有一个索引在删除过程中保持不成对。 具体来说，我们确保不要选择太密集的字符，因为任何四个连续位置的块都可能会破坏中间的两个字符。 
4. 在保持约束的同时，尽早贪婪地选择匹配。 如果在任何时候我们无法在 s 中找到有效的下一个匹配项，我们将返回 NO。 
5. 如果我们成功匹配 t 的所有字符，则返回 YES。 

为什么这种方法有效来自结构不变量：在任何操作序列之后，剩余的字符形成 s 的子序列，其中没有幸存的字符曾经是在此过程中选择的任何长度为 4 的窗口的中间元素。 t 的任何有效构造都对应于这样的子序列，并且任何遵守间距约束的子序列都可以通过选择在其周围删除而不消除所选位置的操作来实现。 因此，可行性精确地降低为寻找受约束的子序列嵌入。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def possible(s, t):
    n, m = len(s), len(t)
    j = 0
    last = -10**18

    for i, ch in enumerate(s):
        if j < m and s[i] == t[j]:
            if i - last >= 2:
                last = i
                j += 1
                if j == m:
                    return True
    return j == m

def solve():
    T = int(input())
    for _ in range(T):
        s = input().strip()
        t = input().strip()
        print("YES" if possible(s, t) else "NO")

if __name__ == "__main__":
    solve()
```该实现使用带有附加间距约束的贪婪子序列匹配。 变量`last`跟踪 s 中最后选择的位置。 我们仅接受与先前选择的位置不相邻的新匹配，以确保没有两个所选字符落入可以通过重叠长度 4 删除同时破坏的配置中。 

指针`j`跟踪 t 的进度。 如果到达最后，我们就成功嵌入了 t。

 ## 边缘情况

 一种边缘情况是 t 中的字符密集出现在 s 中，迫使选择相邻的字符。 例如，s =“aaaaa”，t =“aaa”。 该算法选择索引 0、2、4。间距规则允许这样做，因为每个选定的索引至少相距 2，因此不会出现冲突。 这对应于能够始终避免将选定的字符放置在可移动的中间位置内。 

另一种边缘情况是 t 与 s 相同。 由于不需要删除，所以每个字符都被取走，并且由于没有引入冲突的删除结构，因此自然满足间距。 

朴素子序列匹配的失败情况是 s =“ababa”，t =“aaa”。 简单的子序列检查可能会接受位置 0、2、4。然而，在重复的 4 窗口删除下，相邻结构可以以打破天真的假设的方式消除中间位置。 间距规则确保可以通过避免重叠破坏性窗口来保留任何选定的配置。
