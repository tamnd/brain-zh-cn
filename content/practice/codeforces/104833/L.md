 ## 问题理解

 我们正在模拟一个回合制的生存过程，其中角色以初始生命值开始，并在一系列回合中反复失去生命值。 不同的是，每轮结束时施加的伤害并不是固定的。 相反，这取决于到目前为止已经发生了多少次火灾损失。 

更准确地说，我们处理一个长度的数组$n$。 每个元素告诉我们当前回合是否触发额外的“火焰堆栈”。 如果是这样，全局计数器就会增加。 处理完该轮的事件后，角色受到的伤害等于该计数器的当前值。 品格从健康开始$x$，并且我们必须确定生命值降至零或更低的第一轮，或者报告这种情况永远不会发生。 

关键结构是损害是累积的并且随着时间的推移单调增加。 每次发生火灾事件时，所有后续回合都会变得更加危险，因为每轮伤害会永久增加。 

这些限制促使我们采用线性扫描解决方案。 和$n \le 10^6$，任何二次模拟，例如每轮从头开始重新计算累积伤害，都太慢了。 我们必须维护运行状态并以恒定的时间更新每个元素。 内存限制是标准的，因此存储数组没问题，但额外的重新计算则不然。 

当角色在施加伤害后恰好在圆形边界处死亡时，会出现微妙的边缘情况。 死亡检查必须在施加当前回合的伤害之后进行，而不是之前。 另一个特殊情况是，当伤害在过程后期变得很大时，这意味着早期回合可能看起来很安全，但后来的爆发可能会突然结束游戏。 最后，如果即使在最大累积伤害之后生命值也不会低于零，我们必须正确输出在所有回合中生存持续下去。 

## 方法

 简单的模拟遵循字面上的规则。 我们维持当前的生命值和火力计数器。 对于每一轮，如果数组值为 1，我们将增加计数器，然后从生命值中减去计数器。 每次减法后，我们都会检查健康状况是否已降至零或更低。 这是正确的，因为它反映了所描述的确切过程。 

暴力解释在时间上仍然是线性的，但不太仔细的版本可能会通过在每一步扫描所有先前的火灾事件来重新计算“当前损害”。 这将使每轮成本$O(n)$，导致$O(n^2)$最坏情况下的总操作。 和$n = 10^6$，这变得不可行。 

关键的观察结果是圆形损伤$i$仅取决于火灾事件的前缀计数。 该前缀计数可以增量地维护。 一旦我们意识到这一点，每一轮就变成一个恒定时间更新：如果需要，增加计数器，从健康中减去它，并检查是否终止。 

这将整个过程减少为通过数组的单次传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（每轮重新计算伤害）|$O(n^2)$|$O(1)$| 太慢了|
 | 最优前缀模拟 |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们维护两个变量：当前生命值和累积火力计数器。 

1. 初始化`hp = x`和`burn = 0`。 变量`burn`表示从现在开始，如果没有进一步的火灾出现，每轮将施加多少伤害。 
2. 从第一轮到最后一轮迭代数组。 
3. 如果当前值为1，则递增`burn`1. 这反映出未来所有回合都变得更加危险。 
4. 减法`burn`从`hp`。 该模型模拟了回合结束时的伤害应用。 
5.如果`hp <= 0`，输出当前轮索引并立即停止。 最早的一轮是必需的，所以我们不能继续。 
6. 如果我们完成所有回合而没有`hp`变为非正，输出保证生存。 

正确性取决于损害程度完全取决于迄今为止发生的火灾事件的数量。 每次火灾事件都会使所有未来的损害永久增加一个单位，因此`burn`始终等于火灾指示器的前缀和。 

### 为什么它有效

 在任何一轮$i$，所施加的伤害正是指数的数量$j \le i$这样$a_j = 1$。 该算法明确地维护这个数量`burn`。 由于健康状况在每个步骤中都会根据此前缀值确定性地减少，因此模拟与问题中描述的过程完全匹配。 因为我们在该轮应用正确的伤害后立即检查死亡，所以第一次健康状况变得非积极时一定会被报告。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, x = map(int, input().split())
a = list(map(int, input().split()))

hp = x
burn = 0

for i in range(n):
    if a[i] == 1:
        burn += 1
    hp -= burn
    if hp <= 0:
        print("YES")
        print(i + 1)
        break
else:
    print("NO")
```实现直接反映了算法。 该循环使用Python`for-else`结构，以便只有在没有发生中断时才会触发“NO”情况。 指数`i + 1`从从零开始的索引转换为输出所需的从一开始的轮编号。 

一个常见的错误是在更新燃烧计数器之前减去伤害。 这会将所有伤害转移一轮并产生不正确的早期死亡结果。 另一个微妙之处是确保当健康状况变得不乐观时立即发生休息； 继续下去会错误地报告稍后的死亡回合。

 ## 边缘情况

 一个重要的边缘情况是当角色开始时生命值非常低并且第一个火灾事件立即出现。 用于输入`1 1 / 1`，烧伤在受到伤害前变为1，生命值立即降至零。 该算法首先正确更新燃烧，然后施加伤害，在第一轮产生死亡。 

另一种边缘情况是所有值都为零时。 燃烧变量永远不会增加，因此不会造成任何伤害。 算法处理所有轮次并通过loop-else路径退出，正确输出生存。 

第三种情况涉及早期的密集火灾事件。 用于输入`4 3 / 1 1 1 1`，烧伤进化为1、2、3、4，而生命值相应降低。 该过程确保一旦燃烧超过剩余生命值，就可以检测到准确的回合，而不会出现超调，因为检查会在减法后立即进行。 

最后一个微妙的情况是最后一轮发生死亡。 循环在终止前仍然执行检查，确保报告正确的轮索引而不是默认为“NO”。
