 ## 解决方案
 ## 问题理解

 我们在一堆球上玩减法游戏。 游戏状态由当前球数定义，例如$a$。 在玩家的回合中，允许的移动大小由当前状态的函数确定：计算$a$，称之为$x$。 玩家可以移除 1 到 1 之间任意数量的球$\min(a, x)$，包含在内。 采取行动使堆空的玩家立即获胜。 

每个测试用例给出一个初始编号$n$，并且我们必须确定第一个玩家（A）在最佳玩法下是否强制获胜。 

二维方面的约束很大。 最多可以有$10^6$测试用例，以及每个$n$也可达$10^6$。 这立即排除了任何每个查询的模拟。 甚至$O(n)$每个测试用例都是不可能的，甚至$O(n \log n)$每个查询都会太慢。 任何解决方案都必须有效地预处理所有值直至最大值$n$一次。 

出现微妙的边缘情况时$n$很小，因为数字和可以大于或等于$n$。 例如，当$n = 1$，数字和为1，所以玩家只能取1，立即获胜。 什么时候$n = 10$，数字和为 1，因此只有一步存在，这使得它的行为与直观的“拿走任何”游戏不同。 这些边界情况很重要，因为移动范围取决于状态本身，而不仅仅是固定参数。 

另一个重要的失败模式来自于假设一个经典的外卖游戏具有固定的$k$。 在这里，最大移动量在每个位置都会发生变化，因此标准周期性参数（例如模）$k+1$不适用于全球。 

## 方法

 暴力解决方案将从每个起始值模拟游戏$n$。 对于每个州$a$，我们会尝试所有可能的动作$k$从 1 到$\min(a, \text{digitSum}(a))$，递归检查结果头寸是否正在亏损。 这形成了一个标准的游戏 DP，但在最坏的情况下每个状态可能会分支多达 54 个转换（因为数字总和为$10^6$最多 54)。 超过所有州$10^6$，这大约产生$5 \times 10^7$转换、递归或重复重新计算会进一步推动它，使其在严格限制下的 Python 中处于边缘或缓慢。 

关键的观察是我们不需要以递归方式单独探索每个动作。 如果存在至少一次向亏损头寸的移动，则该头寸为盈利头寸。 由于所有移动都进入连续状态$[a - s(a), a - 1]$，我们只需要知道该区间内是否存在失败状态即可。 这将问题转化为维护丢失状态的前缀摘要，从而允许在预处理后进行恒定时间范围检查。 

我们定义一个 DP 数组，其中每个状态要么获胜，要么失败。 我们按升序计算状态，并且对于每个位置，我们检查可达状态的间隔是否包含任何丢失状态。 如果是，则当前状态为获胜； 否则就是失败。 丢失状态的前缀和使得此检查的复杂度为 O(1)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力DFS DP | O(n · 数字和) | O(n) | 太慢了 |
 | 带有范围查询的前缀 DP | O(n + T) | O(n) | 已接受 |

 ## 算法演练

 我们计算所有值的结果，直到最大值$n$出现在输入中。 

1. 预先计算所有整数的数字和$10^6$。 这确保了可以在 O(1) 时间内获得每个状态的移动范围。 
2. 初始化一个DP数组，其中`dp[i]`表示当前玩家是否有从以下位置开始的获胜策略$i$。 还维护一个前缀数组`pref`， 在哪里`pref[i]`计算有多少个亏损头寸$[0, i]$。 
3. 设置基础状态`dp[0] = False`，因为没有剩余的动作。 在前缀数组中标记它。 
4. 迭代自$i = 1$到最大值。 对于每个$i$, 计算$s = \text{digitSum}(i)$。 
5. 玩家可以在区间内移动到任意状态$[i - s, i - 1]$。 只有当所有这些状态都获胜时，当前状态才是失败的，这相当于说在这个区间内没有失败的状态。 
6. 使用前缀和在 O(1) 中检查此条件：

 如果`pref[i-1] - pref[max(0, i-s-1)] == 0`，然后标记`dp[i] = False`， 否则`dp[i] = True`。 
7. 相应地更新前缀和并继续。 

填完表后，每个查询都会在 O(1) 内得到回答。 

### 为什么它有效

 每个位置仅依赖于严格较小的位置，因此按升序处理可确保正确性。 关键的不变量是`dp[i]`完全由是否存在至少一个可从其到达的失败状态决定。 前缀数组正确地维护了任何区间内失败状态的计数，因此决策规则与公正游戏中获胜位置的定义完全匹配：如果一个位置至少有一次移动到失败状态，则该位置获胜，否则失败。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXN = 10**6

digit_sum = [0] * (MAXN + 1)
for i in range(1, MAXN + 1):
    digit_sum[i] = digit_sum[i // 10] + (i % 10)

dp = [False] * (MAXN + 1)
pref = [0] * (MAXN + 1)

dp[0] = False
pref[0] = 1  # count of losing positions

for i in range(1, MAXN + 1):
    s = digit_sum[i]
    left = i - s
    if left < 0:
        left = 0

    # count losing positions in [left, i-1]
    losing_in_range = pref[i - 1] - (pref[left - 1] if left > 0 else 0)

    if losing_in_range == 0:
        dp[i] = False
    else:
        dp[i] = True

    pref[i] = pref[i - 1] + (0 if dp[i] else 1)

t = int(input())
out = []
for _ in range(t):
    n = int(input())
    out.append("A" if dp[n] else "B")

print("\n".join(out))
```该代码在线性时间内预先计算数字和，然后从 1 向上构建 DP 数组。 关键的微妙之处在于维护丢失状态的前缀计数，以便每个间隔查询变得恒定时间。 前缀数组存储失败位置的计数，而不是获胜位置的计数，因为转换条件自然地表达为“是否存在可用的失败动作”。 

答案映射直接如下：如果`dp[n]`为真，起始玩家可以强行获胜，否则第二玩家获胜。

现在考虑一个稍大的结构，其中数字和更严格地限制可达性。 同样的机制也适用：一旦仓位无法达到任何亏损状态，它就会亏损，从而产生定义整个 DP 的连锁反应。 

这些跟踪表明，每个步骤的决策仅取决于间隔信息，而不取决于单独的转换，这就是前缀聚合就足够的原因。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MAXN = 10**6
    digit_sum = [0] * (MAXN + 1)
    for i in range(1, MAXN + 1):
        digit_sum[i] = digit_sum[i // 10] + (i % 10)

    dp = [False] * (MAXN + 1)
    pref = [0] * (MAXN + 1)

    dp[0] = False
    pref[0] = 1

    for i in range(1, MAXN + 1):
        s = digit_sum[i]
        left = max(0, i - s)
        losing = pref[i - 1] - (pref[left - 1] if left > 0 else 0)
        dp[i] = losing != 0
        pref[i] = pref[i - 1] + (0 if dp[i] else 1)

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append("A" if dp[n] else "B")
    return "\n".join(out)

# boundary cases
assert run("1\n1\n") == "A"
assert run("1\n10\n") in ["A", "B"]

# small structure
assert run("3\n1\n2\n3\n") == "A\nA\nA"

# max boundary single test
assert run("1\n1000000\n") in ["A", "B"]

 ## 边缘情况

 对于$n = 1$，数字和为 1，所以唯一的做法就是取 1 并立即获胜。 DP 将状态 1 标记为获胜，因为它可以到达状态 0，即失败。 

为了$n = 10$，数字和再次为 1，因此唯一的移动就是 1，这将问题简化为状态 1 是输还是赢。 由于已知状态 1 会获胜，因此状态 10 会失败，并且前缀逻辑正确地捕获了这种依赖性。 

对于像这样的大值$n = 999999$，位数和为54，因此每个状态可以达到很宽的区间。 基于前缀的检查有效地评估该间隔中是否存在任何丢失状态，而无需显式迭代所有 54 个转换，从而保持正确性和速度。
