 ## 解决方案
 ## 问题理解

 我们被要求构造一个仅包含以下内容的二进制字符串`0`和`1`使得子序列的数量等于`01`正是`m`。 一个子序列`01`意味着我们选择一个`0`字符串中的某处和`1`稍后在字符串中。 每对这样的对都为总数贡献一个。 

更具体地重新构造，每个`0`“看到”所有`1`出现在它之后，并贡献了许多有效的子序列。 因此，字符串的总价值是其右侧有多少个 0 的总和。 

任务是建设性的：给定`m`最多$10^9$，我们必须输出最多长度的任何有效二进制字符串$10^5$正好产生这个值。 

约束足够小，使得$O(n)$建筑甚至$O(\sqrt{m})$推理就足够了。 任何平方$10^5$会太慢，但我们不会被要求搜索或优化所有字符串，而只是确定性地构造一个字符串。 

出现微妙的边缘情况时`m = 0`。 在这种情况下，任何不带`0`之前`1`作品，例如`"0"`,`"1"`， 或者`"000"`。 然而，粗心的构造总是假设至少一个`1`或强制执行固定结构可能会意外引入`01`配对并产生正值时`m`为零。 

## 方法

 暴力方法会尝试逐步构造一个字符串并维持当前的数量`01`每次插入后的子序列。 在每一步中，我们可以尝试添加`0`或者`1`并重新计算贡献。 这很快就变得不可行，因为重新计算长度字符串的值$n$成本$O(n)$，探索所有可能性将导致指数分支。 即使是在每一步重新计算计数的贪婪变体也会降级为$O(n^2)$，这对于$10^5$。 

关键的观察结果是，值的结构以一种非常具体的方式呈线性。 如果我们修复多少`1`s 出现在一个块之后`0`s，那么每个`0`在该块中贡献了完全相同的数量。 这建议将字符串分组为块，其中剩余的数量`1`s 逐步减小。 

我们可以以零和单个交替块的形式构造字符串：```
0...0 1 0...0 1 0...0 1 ...
```假设有`K`总共有几个。 然后前面放置的每个零`i`- 第一个贡献完全`(K - i + 1)`到答案，因为这就是它后面出现的数量。 这将问题转化为表示`m`作为零的加权计数的总和，其中权重是`K, K-1, ..., 1`。 

如果我们选择`K`大约$O(\sqrt{m})$，那么我们可以贪婪地分解`m`使用这些重量，确保我们不超过长度限制。 这是可行的，因为权重形成了一个完全递减的基础，并且我们总是可以首先减去尽可能多的大贡献。

 | 蛮力 | 指数 /$O(n^2)$|$O(n)$| 太慢了|

 ## 算法演练

 我们现在显式构建字符串。 

### 算法演练

 1. 选择一个值`K`这样$K \approx \sqrt{2m}$，通常约为 450$m \le 10^9$。 这是数量`1`我们将把 s 放在最后的字符串中。 目标是使权重从`K`下降到`1`足以代表`m`。 
2. 将最终的字符串视为交替的段：一组零，然后是一个`1`, 重复`K`次。 每个`1`分隔块并定义其右侧剩余的块数。 
3. 对于每个位置`i`从`1`到`K`,决定有多少个零`z[i]`放置在之前`i`-th`1`。 这些零中的每一个都准确贡献`(K - i + 1)`到最终的答案。 
4. 处理权重由大到小。 对于重量`w = K - i + 1`，取尽可能多的零：$$z[i] = \min\left(\frac{m}{w}, \text{remaining capacity}\right)$$然后减去`z[i] * w`从`m`。 这种贪婪的选择确保我们减少`m`首先快速使用大贡献。 
5. 处理完所有权重后，`m`变为零。 通过编写构造最终的字符串`z[1]`零，那么`1`， 然后`z[2]`零，那么`1`， 等等。 
6.如果原来的`m`为零，输出单个字符串，例如`"0"`。 

### 为什么它有效

 该结构将目标值编码为权重的线性组合`K, K-1, ..., 1`，其中每个权重对应于给定块中放置零时剩余的数量。 由于每个整数大约$K(K+1)/2$可以使用这些递减的权重来贪婪地表达，并且$K$选择足够大，使该总和超过$m$，表示总是成功。 每个零根据其块位置独立贡献，因此总和与构造的分解完全匹配`m`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    m = int(input().strip())

    if m == 0:
        print(1)
        print("0")
        return

    # choose K ~ sqrt(2m)
    K = 1
    while K * (K + 1) // 2 < m:
        K += 1

    z = [0] * K

    # greedy decomposition from large weights to small
    rem = m
    for i in range(K):
        w = K - i
        if w == 0:
            break
        take = rem // w
        z[i] = take
        rem -= take * w

    # build string
    res = []
    for i in range(K):
        res.append("0" * z[i])
        if i < K - 1:
            res.append("1")

    print(sum(z) + K - 1)
    print("".join(res))

if __name__ == "__main__":
    solve()
```该代码首先直接处理零情况，因为任何字符串都没有有效的`0`前`1`成对是可以接受的。 对于积极的`m`，它计算合适的个数`K`，然后贪婪地分配每个 1 之前应出现多少个零。 

关键的实现细节是每个块的权重完全由其右侧的位置决定。 循环保持剩余值`rem`，确保每个作业都是有效且独立的。

 ## 边缘情况

 对于`m = 0`，该算法完全绕过构造并输出单个`0`。 这可以避免意外引入`01`对，这在任何涉及至少一个的交替结构中都是不可避免的`1`。 

对于非常大的`m`，所选择的`K`仍然很小（大约 450），因此即使生成许多零，总长度仍然有限​​，因为每个重量单位都会被贪婪地消耗，从而防止块大小爆炸。 

对于小`m`例如`1`或者`2`，贪婪分解仅将零分配给最高权重的位置，从而产生一个紧凑的字符串，其中只有几个仔细放置的零对总计数有贡献。
