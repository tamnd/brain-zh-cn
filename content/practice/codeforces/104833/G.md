 ## 解决方案
 ## 问题理解

 我们给出了一个应用于从 1 到极限的每个整数的函数$n$，对于每个整数，我们决定它是否贡献 1 或 0 值。每个测试用例的最终答案是满足特定结构属性的范围内的整数总数。 

定义中隐藏的条件是当该数字达到大于 1 的某个整数幂时是否变得“结构良好”。用更具体的术语重写它：对于给定的整数$x$，我们检查是否存在整数指数$k > 1$这样$x$可以用百分比表示$k$有理数的 - 次方。 对于整数，这会分解为更熟悉的情况：$x$一定是一个完美的幂，这意味着它可以写成$a^k$对于整数$a \ge 2$和$k \ge 2$。 

所以任务简化为计算有多少个数字$[1, n]$是至少 2 的指数的完美幂。 

输入约束$n \le 10^{18}$是解决方案的主要驱动力。 对所有数字进行直接迭代$n$这是不可能的，因为即使每个测试用例进行线性扫描也会远远超出允许的操作。 任何可行的方法都必须只枚举完美幂的稀疏结构。 

一个微妙的边缘情况是，许多数字具有完美幂的多种表示形式。 例如，64 可以写为$2^6$,$4^3$， 和$8^2$。 如果不进行重复数据删除，独立计算每个指数的简单方法会过度计算这些数字。 

另一个边缘情况是$x = 1$。 自从$1 = 1^k$对于任何$k$，它始终是完美幂并且必须只包含一次。 

## 方法

 强力解释将检查每个数字$x \le n$并尝试所有指数$k \ge 2$，验证是否$x$是一个完美的$k$次幂。 这将需要对每个数字重复进行整数根检查，导致粗略地$O(n \log n)$每个测试用例的工作，这对于$n \le 10^{18}$。 

关键的观察是完美的幂极其稀少。 而不是迭代$x$，我们可以迭代生成对$(a, k)$。 每个有效数字都是由某个碱基产生的$a \ge 2$提升到某个指数$k \ge 2$，并且指数有界，因为$a^k \le n$意味着$k \le \log_2 n$，最多为 60。 

这将问题从扫描一个巨大的区间转移到枚举一小组指数层。 对于每个指数$k$，我们可以计算所有有效的基数$a$这样$a^k \le n$，并收集所有结果值。 需要一个集合来消除由像 64 这样的数字以多种指数形式出现而引起的重复。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n \log n)$|$O(1)$| 太慢了 |
 | 枚举权力 |$O(n^{1/2} + n^{1/3} + \dots)$|$O(\text{count})$| 已接受 |

 ## 算法演练

 ### 最优策略

 1. 认识到每个有效数字都具有以下形式$a^k$在哪里$k \ge 2$和$a \ge 2$。 这将问题从过滤数字重新定义为生成数字。 
2. 观察指数$k$不能很大，因为$2^k \le n$。 所以我们只需要考虑$k$from 2 up to 60.
 3. 对于每个指数$k$，计算最大整数基数$a$这样$a^k \le n$。 这可以使用整数根提取来完成。 
4. 对于每个有效碱基$a \ge 2$, 计算$a^k$并将其插入到集合中。 该集合确保重复项如$64 = 8^2 = 4^3 = 2^6$只计算一次。 
5. 处理完所有指数后，测试用例的答案就是集合的大小。 

### 为什么它有效

 每个计数的整数都会被插入，因为它至少有一个幂表示形式$a^k$和$k \ge 2$。 相反，每次插入都对应于该范围内的有效完美功率。 该集合保证了唯一性，因此每个数字只贡献一次，无论它有多少个指数基分解。 因为超过 60 的每个指数都是不可能的$n \le 10^{18}$，没有遗漏任何有效号码。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def kth_root(n, k):
    lo, hi = 1, int(n ** (1 / k)) + 2
    while lo <= hi:
        mid = (lo + hi) // 2
        v = mid ** k
        if v <= n:
            lo = mid + 1
        else:
            hi = mid - 1
    return hi

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        seen = set()

        for k in range(2, 61):
            a = kth_root(n, k)
            for base in range(2, a + 1):
                seen.add(base ** k)

        print(len(seen))

if __name__ == "__main__":
    solve()
```该实现依赖于迭代指数并生成所有相应的基数。 辅助函数使用二分搜索计算每个指数的最大有效基数，避免提取根时的浮点精度问题。 

嵌套循环结构可能看起来很重，但实际上，值收缩得非常快，如下所示$k$成长。 为了$k \ge 6$，有效碱基的范围变得非常小，使得总生成易于管理。 

## 工作示例

 考虑$n = 16$。 

| k | 最大基数 | 产生的价值|
 | --- | --- | --- |
 | 2 | 4 | 4、9、16 |
 | 3 | 2 | 8 |
 | 4 | 2 | 16 | 16

 该集合累加为 {4, 9, 16, 8}。 最终答案是4。 

此跟踪显示了如何自然地删除由多个指数产生的重复项（例如 16）。 

现在考虑$n = 10$。 

| k | 最大基数 | 产生的价值|
 | --- | --- | --- |
 | 2 | 3 | 4, 9 |
 | 3 | 2 | 8 |

 该集合变为 {4, 9, 8}，给出答案 3。 

这表明 10 以内的所有完美幂都被精确捕获一次，没有丢失或重复的条目。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(\sum_{k=2}^{60} \sqrt[k]{n})$| 每个指数最多生成$n^{1/k}$基地|
 | 空间|$O(m)$| 将每种独特的完美力量存储一次 |

 的成长$n^{1/k}$下降很快，因此即使对于$n = 10^{18}$。 这确保了解决方案能够轻松地满足限制。

 ## 边缘情况

 最重要的边缘情况是具有多个指数表示的数字。 例如，输入$n = 64$包括 64 个$2^6$,$4^3$， 和$8^2$。 该算法生成所有三种形式，但该集合仅确保一种计数。 执行期间，64 会在 k=2、k=3 和 k=6 处插入，但后面的插入将被忽略。 

另一个边缘情况是$n = 1$。 由于 1 等于$1^k$为所有人$k$，它始终包含在内。 循环仍尝试生成，但仅插入 1 次。 

最后非常大$n$价值观像$10^{18}$对于高指数产生极小的有效范围。 例如，在$k = 10$，仅考虑最多 4 个碱基。 这可以防止计算爆炸并保持枚举的严格限制。
