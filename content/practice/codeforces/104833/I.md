 ## 问题理解

 我们对一个非常小的“程序”进行了许多独立的检查：一个整数`x`存储在 32 位有符号的`int`，然后将其转换为某种未知整数类型，并将结果值与给定整数进行比较`y`。 未知类型要么是无符号的，要么是有符号的，在这两种情况下，它的行为都类似于具有环绕溢出的固定宽度模块化类型。 

对于无符号类型，值位于范围内`[0, M]`并且算术是按模进行的`M + 1`。 所以储存`x`意味着将其替换为`x mod (M + 1)`，始终解释为非负数。 

对于有符号类型，值位于`[-M - 1, M]`，并且算术被执行取模`2M + 2`。 存储的残差取模`2M + 2`，然后以通常的补码风格解释：上面的值`M`通过减法向下移动`2M + 2`。 

每个测试都会询问是否存在任何有效类型（有符号或无符号）和有效最大值`M`（不超过10^18）这样转换`x`进入该类型会产生准确的结果`y`。 如果存在这样的配置，我们必须输出一个有效的描述； 否则我们输出`-1`。 

关键的限制是测试用例最多有 100,000 个，因此每个测试在预处理后必须在大致对数或恒定时间内处理。 我们无法尝试搜索`M`。 

出现微妙的边缘情况时`x == y`。 在这种情况下，许多不同的模数都可以工作，包括非常小的模数，例如`M = 0`，而且还有签名配置。 仅检查整除模式的幼稚方法可能会忽略这种微不足道的相等情况，或者通过强制使用不存在的模数结构来错误处理它。 

另一个棘手的情况是当`y`是负数。 无符号类型永远不会产生负结果，因此任何正确的解决方案都必须立即拒绝这种情况下的所有无符号可能性。 然而，有符号类型可能仍然有效，具体取决于如何`y`位于由以下引起的有符号范围内`M`。 

## 方法

 蛮力的想法是尝试所有可能的值`M`最多 10^18 并模拟有符号和无符号解释的转换。 对于每个候选者，我们将计算的模块化图像`x`并检查是否匹配`y`。 这是正确的，因为它直接遵循类型系统的定义。 问题是搜索空间巨大，甚至迭代一个有意义的子集`M`是不可能的。 范围太大，并且映射不能以允许扫描的方式单调地运行。 

关键的观察是转换仅依赖于模运算。 在有符号和无符号的情况下，存储的值完全由`n = M + 1`（未签名）或`n = 2M + 2`（签名）。 转换后的值等于的条件`y`强制一致：`x ≡ y (mod n)`。 

这减少了搜索的问题`M`搜索可能的模数`n`那个鸿沟`x - y`。 一旦我们确定了候选模数，我们只需要验证它是否可以对应于有效的有符号或无符号范围。 

因此，我们只枚举除数，而不是扫描一个巨大的范围`|x - y|`，其大小最多约为 2^32，这意味着在最坏的情况下只有大约 60,000 个除数。

 ## 算法演练

 我们专注于一个具有值的测试用例`x`和`y`。 

1. 计算`d = x - y`。 如果`d == 0`，任何模数原则上都有效，因此我们可以直接构造一个简单的有效类型，例如无符号类型`M = 0`或带符号的类型`M = 0`取决于约束条件。 这是作为特殊情况处理的。 
2.否则采取`|d|`并枚举所有正因数`n`。 每个除数都是一个候选模数，因为条件`x ≡ y (mod n)`必须成立，这相当于`n | (x - y)`。 
3. 对于每位候选人`n`，首先测试是否可以表示无符号类型。 这需要两个条件：`y`必须是非负数并且必须位于`[0, n - 1]`。 如果是的话我们可以设置`M = n - 1`，并且该候选者是有效的。 
4.还是一样`n`，测试它是否可以表示有符号类型。 有符号类型具有模数`n = 2M + 2`， 所以`n`必须是均匀的。 我们计算`M = n / 2 - 1`，并检查是否`y`位于里面`[-M - 1, M]`。 如果是，则该模数对于有符号类型有效。 
5. 如果任何除数产生有效的配置，我们立即输出它。 否则，在穷尽所有除数后，我们输出`-1`。 

每个除数足以检查的原因是模等式完全表征了当`x`和`y`包裹后可以变得相同。 唯一剩下的约束是结果残数是否可以在允许的有符号或无符号范围内解释。 

### 为什么它有效

 转换过程会丢弃有关的所有信息`x`除了其对字体大小取模后的余数。 因此任何有效的解决方案都必须满足`x - y`是该大小的倍数。 这将问题转化为寻找一个模数来除`x - y`并同时承认`y`作为相应数字范围内的有效表示。 因为每个有效类型都对应于一个这样的模数，所以检查所有除数`x - y`既是必要的又是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def get_divisors(n):
    res = []
    i = 1
    while i * i <= n:
        if n % i == 0:
            res.append(i)
            if i * i != n:
                res.append(n // i)
        i += 1
    return res

def solve():
    t = int(input())
    for _ in range(t):
        x, y = map(int, input().split())
        d = x - y

        if d == 0:
            # trivial valid construction
            # unsigned with M = 0 always works
            print("unsigned 0")
            continue

        ad = abs(d)
        divisors = get_divisors(ad)

        found = False

        for n in divisors:
            if d % n != 0:
                continue

            # unsigned case
            if y >= 0 and y <= n - 1:
                print("unsigned", n - 1)
                found = True
                break

            # signed case
            if n % 2 == 0:
                M = n // 2 - 1
                if -M - 1 <= y <= M:
                    print("signed", M)
                    found = True
                    break

        if not found:
            print(-1)

if __name__ == "__main__":
    solve()
```代码首先枚举除数`|x - y|`，因为只有那些模才能满足所需的同余性。 对于每个除数，它首先尝试通过检查是否将其解释为无符号类型`y`适合`[0, n - 1]`。 如果成功的话我们直接输出`M = n - 1`。 

如果未签名失败，我们尝试签名解释。 这需要`n`是偶数，因为有符号范围是对称的并且总是来自以下形式的模`2M + 2`。 然后我们重建`M`并检查是否`y`位于有符号区间内。 第一个有效匹配就足够了，因为该问题允许任何正确答案。 

特殊情况`x == y`是单独处理的，因为每个模数都有效，我们可以安全地输出最小的有效配置。

 ## 边缘情况

 当`x == y`，模约束消失，因为每个模数都除以零。 该算法显式绕过除数搜索并返回一个简单的无符号类型。 例如，输入`0 0`产生`unsigned 0`，对应于所有值都相等的单元素类型。 

什么时候`y`为负数，未签名的候选者将被自动拒绝，因为它们的范围严格为非负数。 例如，`x = 1, y = -1`强制算法仅进行签名检查，并且仅考虑偶数模。 

什么时候`|x - y|`除数很少（例如当它是素数时），循环很快会失败所有候选者，正确生成`-1`无需探索不必要的配置。
