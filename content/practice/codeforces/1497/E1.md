 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 每个测试用例都提供一个正整数数组，我们希望将该数组拆分为尽可能少的连续部分。 每个部分内部的约束不是关于排序或求和，而是关于乘法属性：在单个段内，您永远不能找到两个不同的元素，其乘积是完全平方数。 

当两个数字共享相同的素数指数奇偶校验模式时，乘积就成为完全平方数。 简单来说，如果我们通过删除所有平方因子来减少每个数字，那么如果两个数字的无平方部分相等，则两个数字“冲突”。 仅当段内没有重复的无平方值时，段才有效。 

因此，问题变成了对转换后的数组进行分区任务：我们希望分割序列，以便在每个段内所有无平方签名都是不同的，并且我们最小化此类段的数量。 

约束条件$n \le 2 \cdot 10^5$在所有测试用例中立即排除每个测试中的任何二次方。 我们需要对每个测试用例进行线性或近线性扫描，可能使用具有哈希结构的贪婪策略。 

当数字被中间值“隐藏”后重复出现时，就会出现微妙的失败情况。 例如，在像这样的数组中$[a, b, a]$，如果我们没有跟踪正确的简化表示，我们可能会错误地允许所有三者进入一个片段。 但是，由于相同的无平方部分立即与其自身创建有效的平方积，因此该段必须在第二次出现时分裂。 

另一种边缘情况是当许多数字在去除平方因子后减少到 1 时，例如$1, 4, 9, 16$。 所有这些都折叠为相同的签名，因此每个元素都必须形成自己的段。 任何适用于原始值而不是无平方标准化的解决方案都将在这里失败。 

## 方法

 暴力策略会尝试一切可能的方法来分割数组并检查每个段的有效性。 检查一个段需要验证没有无平方签名重复，这本身可以通过一组来完成。 分区数量呈指数级增长，甚至简化的动态规划公式也会导致$O(n^2)$每个测试用例的转换，远远超出了允许的限制$n$达到$2 \cdot 10^5$。 

关键的观察是，一旦我们修复了一个段，我们必须切割它的唯一原因是我们第一次遇到重复的无平方值。 这将问题变成了贪婪扫描：我们维护当前存在于活动段中的值集。 一旦我们看到集合中已有一个值，我们就被迫结束该元素之前的段并开始一个新的段。 

唯一缺少的因素是如何有效地计算每个数字的无平方签名。 自从$a_i \le 10^7$，我们可以使用筛子预处理所有数字的最小素因数。 然后可以通过除掉重复的素数来减少每个数字，以便只保留奇数指数。 这个标准化步骤至关重要，因为它将乘法约束转变为整数的简单等式约束。 

一旦所有值都转换为无平方形式，问题就变得与将数组分割成最小数量的段相同，这样段内就没有值重复。 这是一个经典的贪心划分问题。

 ## 算法演练

 1. 预先计算每个整数的最小质因数$10^7$。 这允许稍后快速分解，确保每个数字可以在大致对数时间内减少。 
2. 对于数组中的每个数字，通过迭代其素因子并仅保留出现奇数次的素因子来计算其无平方形式。 此步骤将乘法条件转换为简单的等式条件。 
3. 从左到右遍历数组，同时保留当前段中的一组值。 
4. 如果当前元素的无平方值不在集合中，则将其插入并继续扩展段。 
5. 如果它已经在集合中，则关闭该元素之前的当前段，增加段计数，清除集合，并开始一个包含当前元素的新段。 
6. 处理完所有元素后，计算最终的活动段。 

这种贪婪切割正确的原因是，当出现重复的无平方值时，保留该段将立即违反约束。 延迟剪切没有任何好处，因为未来的元素无法追溯修复重复，并且任何尝试推迟剪切的替代分区只会使当前段无效。 

保持的不变性是，在每一步中，当前集合恰好包含正在进行的段中的无平方值，并且它们都是不同的。 每次我们开始一个新的段时，我们都会重置这个不变量，确保不会构造无效的段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXA = 10**7

spf = list(range(MAXA + 1))
for i in range(2, int(MAXA**0.5) + 1):
    if spf[i] == i:
        step = i
        start = i * i
        for j in range(start, MAXA + 1, step):
            if spf[j] == j:
                spf[j] = i

def square_free(x):
    res = 1
    while x > 1:
        p = spf[x]
        cnt = 0
        while x % p == 0:
            x //= p
            cnt ^= 1
        if cnt:
            res *= p
    return res

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    used = set()
    ans = 1

    for v in a:
        sv = square_free(v)
        if sv in used:
            ans += 1
            used.clear()
        used.add(sv)

    print(ans)

if __name__ == "__main__":
    solve()
```筛子构建最小的质因数，因此分解不需要试除。 每个数字都被简化为规范的无平方代表，这是与段有效性唯一相关的东西。 

在扫描过程中，设置`used`代表当前段。 当出现冲突时，清除集合相当于开始一个新的段，我们立即重新插入当前元素，因为它属于新段。 

一个常见的实现错误是忘记重新计算无平方形式，而是使用原始值。 这破坏了正确性，因为在这个问题中像 2 和 8 这样的值应该被认为是相同的。

 ## 边缘情况

 第一种边缘情况是当每个数字在无平方归约后都变为 1 时。 对于像这样的输入$4, 9, 16$，所有值都折叠为相同的签名。 该算法将 1 插入到集合中，然后立即再次遇到它，每次都强制进行切割。 这会为每个元素生成一个段，这符合段内禁止重复的约束。 

另一个边缘情况是重复相同的素数。 对于像这样的数组$2, 2, 2$，无平方形式始终为 2。第一个元素开始一个段，第二个元素触发剪切，然后重复该过程。 贪婪重置可确保正确性，因为任何段都不能合法地包含多次出现的 2。 

第三种边缘情况是混合分解，其中值不同但间接共享无平方形式，例如$8, 2, 18$。 这里 8 减少到 2，而 2 本身就是 2，因此即使原始值看起来不同，冲突也会立即发生。 归一化步骤保证算法仍然正确检测重复。
