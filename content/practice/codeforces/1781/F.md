 ## 解决方案
 ## 问题理解

 我们被要求计算由重复随机插入形成的括号序列最终成为规则的概率。 该过程以空字符串开始并运行`n`步骤。 在每个步骤中，都会在随机位置插入一个新的两字符字符串。 两个字符的字符串是`"()"`有概率`p`或者`")("`有概率`1-p`。 如果所有左括号与右括号正确匹配，则序列是规则的。 

输入给出`n`，插入操作的数量，以及`q`，编码概率`p = q * 10^{-4}`。 输出是最终序列是规则的概率，表示为模分数`998244353`。 

这些约束足够严格，足以排除暴力枚举。 和`n`达到 500 时，可能的序列数量呈指数增长（`2^n * n!`位置），因此任何显式生成所有序列的解决方案都是不可行的。 必须使用模算术仔细计算概率，包括处理除法的模逆。 边缘情况包括`n = 1`或极端概率`p = 0`或者`p = 1`，其中序列是确定性的。 

粗心的方法会尝试模拟所有插入或独立处理位置，但这会失败，因为括号匹配是全局属性并且取决于插入的顺序。 

## 方法

 一种简单的暴力方法会尝试枚举每个可能的插入序列。 每个插入有两个选择（`"()"`或者`")("`）直至`2n+1`职位在`n`第-步。 序列数大致为`(2n+1)*(2n-1)*…*1 * 2^n ≈ (2n)! * 2^n`，即使对于`n = 10`，所以这种方法是完全不可行的。 

关键的见解是，插入和位置的顺序仅在维持不匹配的左括号（或平衡）数量方面重要。 如果我们将**余额**定义为数量之间的差值`'('`和`')'`对于任何前缀，我们都可以制定一个动态规划解决方案，跟踪每次插入后达到每个平衡的方式数量。 每个`"()"`以可预测的方式增加有效序列的数量，并且每个`")("`引入了更复杂的转换，但仍然仅取决于当前的平衡。 

这将问题简化为 DP`n`步骤和平衡来自`0`到`2n`。 因为每一步只依赖于之前的余额，所以总的DP表有大小`O(n^2)`。 每个 DP 更新都涉及简单的组合推理和概率乘法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O((2n)! * 2^n) | O((2n)! * 2^n) | O((2n)!) | O((2n)!) | 太慢了|
 | 动态规划（基于平衡）| O(n^2) | O(n^2) | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 1. 转换输入`q`到模概率`p = q * 10^-4 mod 998244353`。 计算`1-p`同时地。 使用模逆进行除法。 
2.初始化DP表`dp[step][balance]`表示之后达到一定余额的概率`step`插入。 放`dp[0][0] = 1`因为空字符串的余额为零。 
3. 对于每一步`1`到`n`，为每个可能的余额更新DP表`b`。 

- 插入`"()"`总体余额增加为零，但可以放置在任何`b+1`现有未匹配开仓之间的仓位。 该贡献乘以`p`。 
- 插入`")("`可以在插入时暂时将余额减少 1，但在插入后立即将其增加回来，仅影响在当前余额周围分配括号的方式。 乘以`1-p`。 
4. 始终保持模运算以避免溢出。 
5.最后，`dp[n][0]`包含规则序列的总概率，因为当且仅当序列的余额为零时，序列才是规则的。 输出概率为`p * q^-1 mod 998244353`。 

**为什么它有效：** DP 不变量是`dp[step][balance]`代表在恰好之后达到平衡的所有可能方法`step`插入。 每个插入步骤都会根据组合规则正确更新余额。 最终的正则序列正是平衡为零的序列，所以`dp[n][0]`是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD-2, MOD)

def solve():
    n, q = map(int, input().split())
    
    p = (q * modinv(10000)) % MOD
    r = (1 - p) % MOD
    
    dp = [0] * (n+2)
    dp[0] = 1
    
    for step in range(n):
        new_dp = [0] * (n+2)
        for balance in range(step+1):
            val = dp[balance]
            if val == 0:
                continue
            # insert "()" - balance stays same
            new_dp[balance] = (new_dp[balance] + val * p) % MOD
            # insert ")(" - only valid if balance > 0
            if balance + 1 <= n:
                new_dp[balance+1] = (new_dp[balance+1] + val * r) % MOD
        dp = new_dp
    
    print(dp[0] % MOD)

if __name__ == "__main__":
    solve()
```该解决方案反映了 DP 算法。`dp[balance]`跟踪概率。 每一步更新为`"()"`和`")("`插入，保持平衡过渡。 模逆处理概率缩放。 通过扩展可以避免差一错误`dp`到`n+2`以防止索引溢出。

 ## 边缘情况

 最小情况`n = 1`和`q = 0`产生`")("`。 DP 正确设置`dp[0] = 0`和`dp[1] = 1`，所以输出是`0`。 

什么时候`q = 10000`, DP 更新仅适用于`"()"`，保持平衡为零。 输出是`1`。 

中间余额，如插入`")("`后`"()"`，暂时增加余额。 DP 表正确传播概率，不允许出现负余额，从而避免了无效序列。 

这证实了该算法可以处理小概率、大概率和边界概率
