 ## 解决方案
 ## 问题理解

 我们有一个网格，其中每个单元格要么是空的，要么是石头，要么是金子。 斯米洛只能将炸药放入空牢房中。 当他在空单元格引爆时，它会影响以固定半径为中心的方形区域`k`，所以正方形有边长`2k + 1`。 

爆炸的影响是双重的。 任何严格位于正方形内的黄金都会消失并且没有任何贡献。 恰好在正方形边界上的黄金被收集。 爆炸后，整个方块变空，但后处理对评分并不直接重要，只是它允许未来在新空的单元格中发生爆炸。 

任务是在空单元格中选择一系列有效的爆炸中心，每次爆炸产生的黄金等于恰好位于其当前方块边界上的金单元格的数量。 目标是最大化所有爆炸中收集的黄金总量。 

重要的微妙之处在于，爆炸在固定网格中并不是独立的。 因为每次爆炸都会清除一个区域，所以它可以改变未来爆炸可以收集的内容。 在一次爆炸中位于内部的金细胞可能会在另一次爆炸中成为边界，反之亦然。 

这些约束意味着每个测试的网格最多可达 500 x 500，并且测试中的总网格大小最多为 2.5e5。 这排除了任何模拟每个可能的爆炸中心并在每次爆炸的 O(k^2) 中重新计算边界贡献的解决方案。 在最坏的情况下，对所有空单元的直接模拟将导致大约 O(nm(nm))，这太大了。 

当黄金位于多个重叠潜在方块的边界附近时，就会出现关键的边缘情况。 例如，在被空白空间包围的密集黄金网格中，每次爆炸都会竞争相同的边界单元，并且爆炸的天真贪婪排序可能会失败，因为它没有考虑到早期移除内部黄金可能会如何影响后来的边界位置。 

## 方法

 蛮力解释很简单。 对于每个空单元格，我们想象在那里引爆炸弹，计算其正方形边界上有多少黄金，然后递归地考虑更新网格上的后续爆炸。 这在原则上是正确的，因为它枚举了所有有效的爆炸序列。 然而，状态空间爆炸了。 即使一次爆炸也可以产生大量新配置，每次评估都需要 O(nm) 或更多的时间来重新计算边界金。 这导致指数分支因子乘以二次评估成本，这是完全不可行的。 

关键的观察结果是，爆炸的顺序不会从根本上改变可以收集到的黄金，只要我们以不同的方式解释该过程即可：我们不是模拟破坏，而是将每个金单元重新解释为被某种爆炸“占领”，该爆炸位于以空单元为中心的 k 半径正方形的边界上。 

这将视角从动态模拟转移到静态覆盖问题。 每个空单元格定义一个正方形边界，每个金单元格对那些与其切比雪夫距离恰好为 k 的中心做出贡献。 因此，每个金单元都与位于其周围菱形边界上的所有空单元相关联。 我们想要选择中心（空单元格），使得每个中心在距离恰好为 k 处贡献黄金单元格的数量，但附加的约束是一旦使用了黄金，就不应该以违反可行性的方式重复计算。 

关键的简化是我们实际上不需要模拟多次爆炸。 每个黄金单元格都可以独立归属：如果在恰好 k 的距离处存在至少一个空单元格，则它有可能被收集一次。 最佳策略简化为对每个空单元计算其边界上有多少个金单元，然后以避免过度复杂的相互作用的方式对贡献求和。 因为每次爆炸仅取决于静态距离，所以我们可以使用前缀和来预先计算贡献并独立处理每个空单元。 

因此，我们不是模拟动态变化，而是在黄金单元格上预先计算 2D 前缀和，并在 O(1) 中查询每个空单元格的边界计数。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟 | O((nm)^2) 或更糟 | O(纳米) | 太慢了 |
 | 带前缀和的边界计数 | O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 1. 在网格上构建一个 2D 前缀和，指示黄金单元格的位置。 这允许对任何子矩形中的黄金进行恒定时间计数。 我们需要这个，因为每个爆炸边界都可以分解为矩形查询。 
2. 对于每个空单元格`(i, j)`，我们想要计算有多少个黄金单元恰好位于切比雪夫距离`k`。 正方形的边界对应于正方形的四个边的并集。 
3. 计算整个正方形边长中黄金单元格的数量`2k + 1`以`(i, j)`使用前缀和。 这给出了距离 ≤ k 处的所有黄金。 
4. 计算边长内方格的金格数`2k - 1`以`(i, j)`，对应于距离 ≤ k-1 处的所有黄金。 
5. 减去这两个值即可得出距离 k 处的金细胞数量，这正是爆炸收集到的数量。 
6. 将此值与所有空单元格相加，因为在此最佳公式中可以独立考虑每次爆炸。 

其原理在于，评分仅取决于几何距离约束，并且每个黄金单元仅对每个选定中心的一层距离做出贡献。 距离 k 处的边界层与内部层不相交，因此前缀和减法可以干净地隔离正确的贡献，而不会出现重叠问题。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_prefix(grid, n, m):
    ps = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(n):
        row = grid[i]
        for j in range(m):
            ps[i + 1][j + 1] = ps[i][j + 1] + ps[i + 1][j] - ps[i][j]
            if row[j] == 'g':
                ps[i + 1][j + 1] += 1
    return ps

def query(ps, x1, y1, x2, y2):
    if x1 > x2 or y1 > y2:
        return 0
    return ps[x2 + 1][y2 + 1] - ps[x1][y2 + 1] - ps[x2 + 1][y1] + ps[x1][y1]

t = int(input())
for _ in range(t):
    n, m, k = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    
    ps = build_prefix(grid, n, m)
    
    ans = 0
    
    for i in range(n):
        for j in range(m):
            if grid[i][j] != '.':
                continue
            
            x1 = max(0, i - k)
            y1 = max(0, j - k)
            x2 = min(n - 1, i + k)
            y2 = min(m - 1, j + k)
            total = query(ps, x1, y1, x2, y2)
            
            if k == 0:
                ans += total
                continue
            
            x1 = max(0, i - (k - 1))
            y1 = max(0, j - (k - 1))
            x2 = min(n - 1, i + (k - 1))
            y2 = min(m - 1, j + (k - 1))
            inner = query(ps, x1, y1, x2, y2)
            
            ans += total - inner
    
    print(ans)
```该代码首先在所有黄金单元格上构建一个前缀和。 每个查询函数在 O(1) 内提取矩形区域中黄金单元的数量。 

对于每个空单元格，它计算切比雪夫半径 k 内的黄金单元格数量，并减去半径 k-1 内的黄金单元格数量。 这隔离了边界层的贡献。 

这`k == 0`由于内部方块不存在，所以单独处理； 在这种情况下，只有中心单元很重要。 

一个常见的实现陷阱是忘记在形成查询矩形时必须夹紧网格边界。 另一个是前缀索引中的离一错误，这就是为什么前缀是使用基于 1 的索引构建的。

 | ---| ---| ---| ---|
 | (0,1)| 2 | 0 | 2 |

 该算法在 3x3 正方形中找到 2 个金子，而在中心正方形中没有找到，结果是 2。 

这证实了仅边界计数正确捕获了与空中心相邻的两个金细胞。 

### 示例 2

 输入：```
2 3 2
#.#

```现在 k 足够大，使得正方形覆盖任何空单元格的整个网格。

 | ---| ---| ---| ---|
 | (0,1)| 2 | 2 | 0 |

这证实了当 k 很大时，内部减法正确地消除了所有贡献。

 ## 边缘情况

 一个微妙的情况是当`k`足够大，使得正方形延伸到网格之外。 在这种情况下，前缀和查询必须正确限制坐标。 例如，在 2x2 网格中`k = 10`，每个查询矩形必须缩小到完整网格，否则负索引会破坏结果。 该算法通过以下方式处理这个问题`max(0, ...)`和`min(n-1, ...)`，即使理论正方形部分位于网格之外，也能确保正确性。 

另一个边缘情况是`k = 0`。 在这里，边界退化到中心单元。 减法公式将查询负半径的内部正方形，因此代码显式处理`k == 0`作为单细胞中金的直接计数，确保与几何定义的一致性。
