 ## 解决方案
 ## 问题理解

 我们得到一个数组，描述从 1 到 n 标记的位置上项目的起始排列。 位置 i 最初保存项目 a[i]，最终目标是转换这种排列，使得位置 i 包含每个 i 的项目 i。 

移动物品的唯一方法是通过一组机器人，每个位置放置一个机器人。 机器人可以携带单个物品，如果双手空着，则从当前位置拾取它，在位置之间移动，并且可以选择再次放下或拾取。 仅当 i 和 j 共享大于 1 的公约数时，才可能在位置 i 和 j 之间移动。 

这将问题转化为位置 1 到 n 的可达性问题，其中连通性由 gcd 约束定义。 问题是机器人是否可以使用这些受限移动将物品重新排列成身份配置。 

约束 n ≤ 200000 意味着任何试图显式构建位置对之间的所有边的方法都是不可能的，因为在最坏的情况下，位置对的数量是二次的。 即使迭代所有对并计算 gcd 也会太慢。 该解决方案必须依赖于连接的结构化视图，而不是显式的图形构造。 

当两个位置间接连接但不直接连接时，会出现微妙的边缘情况。 例如，6 通过 2 连接到 10，即使 gcd(6,10)=2 和 gcd(10,15)=5，但 gcd(6,15)=3 也间接连接它们。 仅考虑直接 gcd 边缘的幼稚方法可能会错误地得出结论：移动比实际情况更受限制。 

如果假设每个机器人都可以独立地确定自己的位置，则会发生另一种失败情况。 例如，在像 1 → 8 → 2 → 1 这样的循环中，即使没有任何一个机器人直接“解决”自己的位置，物品也可以在组件内旋转。 

## 方法

 暴力方法将显式构造一个图，其中如果 gcd(i, j) > 1，则每对 (i, j) 都连接，然后运行图遍历以查找连接的组件。 每个节点代表一个位置，边代表允许的机器人运动。 计算组件后，我们将检查每个组件是否包含完全相同的初始项和目标项的多重集。 

原则上这是正确的，因为机器人无法在断开连接的组件之间移动物品。 然而，构建所有边需要检查 O(n^2) 对，并且对于 n = 200000，即使在如此密集的图上使用单个 BFS 或 DFS 也是不可行的。 

关键的观察结果是 gcd(i, j) > 1 相当于 i 和 j 共享至少一个素因子。 我们可以考虑素数引起的连通性，而不是考虑成对的 gcd 检查。 每个数字都属于与其素数因子相对应的所有素数“组”，并且数字通过共享素数连接起来。 这将图转换为数字和素数之间的二部式结构，使我们能够使用不相交的集合联合结构来联合共享任何素数因子的索引。 

一旦我们计算出这种关系下的连通分量，每个分量都必须是自洽的：每个索引 i 必须能够到达其目标位置 a[i]，否则所需的物品无法传输到那里。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（显式图）| O(n²) | O(n²) | 太慢了 |
 | DSU 通过质因数 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们在索引 1 到 n 上构造一个不相交的集合并集结构。 目标是合并通过共享素因子连接的索引。

1. 初始化 DSU，其中每个位置都是其自己的组件。 这表示我们最初假设不可能发生任何运动。 
2. 对于从 1 到 n 的每个数字 i，将其分解为不同的质因数。 由于 n 很大，我们依赖于有效的类似筛子的预处理或试除法直到 sqrt(n)。 
3. 维护一个字典，将每个素数映射到它出现的第一个索引。 当我们在索引 i 处遇到素数 p 时，如果 p 以前没有见过，我们记录 i 作为它的代表。 如果已经看到，我们将 i 与之前存储的索引联合起来。 此步骤通过共享素数构建连接，而无需显式构建边。 
4. 处理完所有索引后，DSU 中的每个连接组件对应于一组位置，机器人可以在这些位置之间自由移动物品。 
5. 最后，对于每个索引 i，我们检查 i 和 a[i] 是否属于同一个 DSU 组件。 如果任何索引不满足此条件，则无法进行转换。 

关键思想是项目只能在 gcd 图的连接组件内移动，并且共享素数上的 DSU 可以正确捕获这些组件。 

### 为什么它有效

 潜在的不变量是，当且仅当两个索引共享一个数字链，其中连续元素共享一个质因数时，两个索引在运动图中是连接的。 DSU 精确地合并了那些至少共享一个素因子的指数，并且联合运算的传递性捕获了间接的 GCD 连接性。 由于每个有效的移动都会保留组件成员身份，因此任何项目都不能跨组件，并且在组件内，重复传输允许任意重新排列。 这使得初始位置和目标位置之间的组件相等既必要又充分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    dsu = DSU(n)

    prime_owner = {}

    def factorize(x):
        res = []
        p = 2
        while p * p <= x:
            if x % p == 0:
                res.append(p)
                while x % p == 0:
                    x //= p
            p += 1
        if x > 1:
            res.append(x)
        return res

    for i in range(1, n + 1):
        primes = factorize(i)
        for p in primes:
            if p not in prime_owner:
                prime_owner[p] = i
            else:
                dsu.union(i, prime_owner[p])

    for i in range(1, n + 1):
        if dsu.find(i) != dsu.find(a[i - 1]):
            print("NO")
            return

    print("YES")

if __name__ == "__main__":
    solve()
```DSU 结构维持指数之间的连接性。 素数分解步骤提取确定基于 gcd 的连通性所需的最小素数集。 映射 prime_owner 确保共享素数的所有数字都合并为单个组件，而无需显式生成边。 

最终循环强制每个项目必须可以在同一连接组件内从其初始位置移动到其所需的最终位置。 

一个常见的实现陷阱是忘记了 Python 中索引是从 1 开始的，而数组 a 是从 0 开始的，这就是使用 a[i - 1] 的原因。

 ## 边缘情况

 一种边缘情况是所有数字都是互质的。 在这种情况下，每个节点在DSU结构中都是孤立的，因此每个位置只能保存自己的项目。 任何不匹配都会立即失败，因为不存在移动边缘。 该算法正确地检测到了这一点，因为没有出现素数并。 

另一个边缘情况是数字通过共享的小素数形成完全连接的结构。 例如，包含许多偶数的序列合并为单个组件。 该算法正确地允许在这个大组件内进行任意排列，因为 DSU 将所有偶数索引合并在一起，从而允许完全重新排列。 

最后一个微妙的情况是连接仅间接存在。 例如，数字 6、10 和 15 通过素数 2、5 和 3 形成一条链。即使某些对的 gcd 为 1，DSU 仍然将它们合并为一个组成部分，从而允许正确的移动。
