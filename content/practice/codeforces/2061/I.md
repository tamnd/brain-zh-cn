 ## 解决方案
 ## 问题理解

 我们需要确定 Kevin 必须投入的最短时间来赢得至少给定数量的对阵 Nivek 的比赛，所有可能的计数从 0 到$n$。 每场比赛都是类型 1，具有固定的时间成本$a_i$凯文保证获胜，或类型 2，如果凯文当前在胜利中不落后，则自动授予凯文。 类型 2 比赛本身并不花费时间，而是取决于 Kevin 之前的胜利。 

输入是一个整数序列，其中$-1$表示类型 2 匹配，任何非负数表示类型 1 匹配的时间成本。 输出是一个长度列表$n+1$，其中$k$-th 元素是确保至少的最短时间$k$获胜。 

鉴于限制条件 -$n$最多$3 \cdot 10^5$每个测试用例，最多$10^4$测试用例 - 任何检查匹配的每个子集或模拟所有可能性的算法都会太慢。 解决方案必须线性扩展或在最坏的情况下扩展$O(n \log n)$每个测试用例。 边缘情况包括所有比赛均为类型 2 时、所有比赛均为类型 1 时或两者混合导致无法达到特定获胜次数时。 

例如，如果输入是`5`并且所有匹配都是类型 2 (`-1 -1 -1 -1 -1`），Kevin 无需花费任何时间就可以赢得所有比赛，因此输出应该是`0 0 0 0 0 0`。 如果所有匹配都是带有成本的类型 1`[3, 2, 5, 4, 1]`，通过选择最便宜的获得给定获胜次数的最短时间$k$匹配，在这种情况下会导致排序成本的累积总和：`0 1 3 6 10 15`。 

粗心的方法可能会尝试按顺序模拟每个匹配并动态决定类型 2 匹配，而不预先计算累积可能性。 这会失败，因为最佳策略通常涉及首先选择特定的类型 1 匹配，然后让类型 2 匹配自动为胜利做出贡献，并且交互是非本地的。 

## 方法

 暴力方法是考虑类型 1 比赛的所有子集，模拟每个子集的类型 2 结果，并记录实现每个可能获胜计数的最短时间。 为了$n$匹配，有$2^n$子集，这是不可行的。 即使我们按匹配类型进行划分，迭代 1 类匹配的所有排列以考虑 2 类结果也会导致指数增长。 

关键的见解是，2 类比赛是免费的，并且如果 Kevin 没有落后，就会自动受益。 这使我们能够单独处理它们。 我们可以先统计Type 2匹配的数量$b$和类型 1 匹配$a_1, \dots, a_m$。 我们按升序对类型 1 成本进行排序。 至少要赢$k$比赛的话，我们可以考虑花时间买最便宜的$x$类型 1 比赛并让类型 2 比赛填补剩余所需的胜利。 具体来说，Kevin 只需要在类型 1 比赛上花费时间，如果$k$超过了他可以利用的第 2 类匹配的数量$k$。 

这将问题简化为对类型 1 成本进行排序并计算前缀和，然后仔细确定每个目标实际需要多少个类型 1 匹配$k$。 每个目标都可以进行评估$O(1)$经过排序和前缀和计算后，得到总体$O(n \log n)$解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 将匹配项拆分为两个列表：类型 1 匹配项及其关联时间，类型 2 匹配项按简单整数计数。 按升序对类型 1 进行排序。 排序确保我们首先将时间花在最便宜的比赛上。 
2. 计算排序后的Type 1 次的前缀和。 这让我们可以快速查询赢得任意数量的类型 1 比赛所需的总时间。 
3. 迭代所需的胜利次数$k$从 0 到$n$。 对于每个$k$，确定 Kevin 必须主动获胜的类型 1 比赛的最小数量。 这是最小的$x$这样$x + \text{Type 2 count} \ge k$和$x \le \text{Type 1 count}$。 如果$k$小于或等于 Type 2 计数，Kevin 无需花费时间。 如果$k$超过Type 2和Type 1匹配的总和，是不可能的，我们可以用-1来标记。 
4.为了可实现的$k$，使用前缀总和数组查找所需类型 1 匹配所花费的总时间。 将其附加到测试用例的输出列表中。 
5. 输出每个测试用例的完整列表。 

为什么有效：在每一步中，算法都会保证我们只在必要时才在类型 1 匹配上花费时间。 如果 Kevin 没有落后，类型 2 比赛会自动促成胜利，因此类型 1 比赛的前缀总和给出所需的最少额外时间。 这确保我们在最短的时间内实现所有可能的目标胜利计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        type1 = sorted([x for x in a if x != -1])
        type2_count = a.count(-1)
        m = len(type1)
        prefix = [0] * (m + 1)
        for i in range(m):
            prefix[i+1] = prefix[i] + type1[i]
        res = []
        for k in range(n+1):
            x = max(0, k - type2_count)
            if x > m:
                res.append(-1)
            else:
                res.append(prefix[x])
        print(' '.join(map(str, res)))

solve()
```该解决方案首先分离类型 1 和类型 2 匹配，对类型 1 进行排序，并预先计算前缀和。 当评估每个$k$，它检查类型 2 是否单独匹配就足够了。 否则，它会根据需要添加最便宜的 1 类匹配。 边缘情况，就像所有类型 2 或类型 1 的匹配一样，自然会被排除在计算之外。 

## 工作示例

 对于输入：```
5
-1 -1 -1 -1 -1
```我们有 5 场 2 类比赛，没有 1 类比赛。 前缀和数组是`[0]`。 迭代$k = 0$到 5，所需的类型 1 匹配是`max(0, k-5) = 0`为所有人$k$。 结果是`[0, 0, 0, 0, 0, 0]`。 

对于输入：```
5
100 -1 -1 -1 1
```类型 1 匹配：`[1, 100]`，输入 2 count = 3。前缀和`[0, 1, 101]`。 

| k | x = 最大值(0, k-3) | 前缀[x] | 结果 |
 | --- | --- | --- | --- |
 | 0 | 0 | 0 | 0 |
 | 1 | 0 | 0 | 0 |
 | 2 | 0 | 0 | 0 |
 | 3 | 0 | 0 | 0 |
 | 4 | 1 | 1 | 1 |
 | 5 | 2 | 101 | 101 101 | 101

 这表明该算法可以正确处理混合物并选择最小成本匹配。
