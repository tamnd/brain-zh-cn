 ## 解决方案
 ## 问题理解

 从 (0) 到 (2^m-1) 的每个整数都可以视为 (m) 位二进制字符串，必要时填充前导零。 函数 (F_{m-1}(a,b)) 计算在第一次不匹配之前从最高有效侧开始有多少个连续位相等。 换句话说，它是两个 (m) 位字符串的最长公共前缀长度或 LCP。 

这些间隔形成整个范围 (0) 到 (2^m-1) 的一个连续分区。 对于每个区间 ([L_i,R_i])，我们从该区间中选择一个代表 (A_i)。 在 LCP 意义上，该代表必须至少与其自己区间内的每个数字 (k) 与其他选定的代表一样相似。 

所有代表选出后，选择的价值就是他们的产品。 我们需要对每个有效选择求这些乘积的总和，模 (100000007)。 

这些约束准确地告诉我们有用的结构必须来自哪里。 一个测试用例中最多有 (2^{17}=131072) 个可能的整数，并且所有测试用例的 (2^m) 之和最多为 (2^{18})。 因此，需要一种在 (2^m) 中接近线性的算法。 (O(2^{2m})) 方法立即不可能，而 (O(2^m m^2)) 方法是合理的，因为 (m\le17)。 

有几种边缘情况很容易破坏粗心的实现。 当(m=0)时，唯一可能的整数是(0)，所以答案是(0)。 例如，```
1
0 1
0 0
```有输出```
0
```假设总是至少有一位的解决方案可能会访问无效的位位置或错误地初始化 DP。 

当只有一个区间时，根本无法与其他代表进行比较。 区间内的每个值都是有效的。 例如，```
1
2 1
0 3
```有答案（0+1+2+3=6）。 不必要地施加相邻间隔条件的解决方案可能会错误地删除候选者。 

边界关系也很重要。 考虑```
1
2 2
0 1
2 3
```有四种可能的选择。 所有四个都满足条件，它们的乘积为 (0\cdot2)、(0\cdot3)、(1\cdot2) 和 (1\cdot3)，给出答案 (5)。 不等式必须是非严格的，因为允许相等的 LCP 值。 

最后，模数是（100000007），而不是（1000000007）。 例如，```
1
17 1
0 131071
```具有不受限制的总和 (8589869056)，其所需的余数为 (89868461)。 使用更熟悉的 (10^9+7) 模数会默默地产生错误的答案。 

## 方法

 直接的方法是枚举每个可能的序列（A_1，\ldots，A_N）。 对于每个序列，我们可以通过将每个选定的代表与每个其他代表在其区间内的数字进行比较来检查原始条件。 这是正确的，因为它遵循字面定义，但序列的数量才是真正的问题。 

如果每个区间包含两个数字，并且有 (65536) 个区间，这在 (m=17) 时是可能的，只需枚举已经给出的选项

 [
 2^{65536}
 ]

 不同的顺序。 这远远超出了任何可以处理的范围。 即使在检查这些序列是否有效之前，枚举本身也是不可能的。 

有用的观察结果来自于将 (F) 解释为 LCP。 假设（a<b<c）。 对于按数字顺序排序的二进制字符串，两个外部值之间的公共前缀由相邻值的公共前缀控制。 特别是，当另一个值向右移动得更远时，具有固定值的 LCP 不能以创建新的更好竞争对手的方式变大。 

这意味着在区间 (i) 内，我们不必将 (A_i) 与每个代表独立进行比较。 与它的近邻进行比较就足够了。 对于左邻居，相关端点是 (L_i)：

 [
 \运算符名称{LCP}(A_i,L_i)
 \ge
 \操作符名称{LCP}(A_{i-1},L_i)。 
]

 对于右邻居，相关端点为 (R_i)：

 [
 \运算符名称{LCP}(A_i,R_i)
 \ge
 \运算符名称{LCP}(A_{i+1},R_i)。 
]

 如果这些不等式成立，那么每一个更远的代表都不会自动变得更好，因为它在相同的数字方向上距离更远。 这将涉及所有代表的全球状况减少为两个局部不平等。 官方社论正是使用了这种LCP还原。 

现在我们可以从左到右构建一个DP。 对于选定的 (A_i)，有四个相关的 LCP 值：

 [
 \开始{对齐}
 a &= \操作符名称{LCP}(A_i,L_i),\
 b &= \操作符名称{LCP}(A_i,R_i),\
 c &= \操作符名称{LCP}(A_i,L_{i+1}),\
 d &= \operatorname{LCP}(A_i,R_{i-1}).
 \结束{对齐}
 ]

 前两个描述了当前代表在其自己的端点上的行为方式。 最后两个准确地描述了处理相邻间隔时所需的信息。 

假设前一个代表的状态为 ((c',b'))。 对于当前候选者，两个邻居条件变为

 [
 c'\le a
 ]

 和

 [
 b'\ge d． 
]

 因此所有兼容的先前状态都位于二维 DP 表的一个矩形中。 二维前缀/后缀和可以让我们在 (O(m^2)) 预处理步骤之后获得该矩形在 (O(1)) 中的总贡献。 

DP 只有 ((m+1)^2) 个状态，并且每个整数恰好属于一个区间。 因此，整个测试用例处理的候选代表总数恰好是（2^m）。 将此与 (O(m^2)) 状态转换相结合，得到 (O(2^m m^2))，这是预期的复杂性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 最坏情况下至少 (2^{65536}) 个序列 | (O(N)) | 太慢了|
 | 最佳 | (O(2^m m^2)) | (O(m^2)) | 已接受 |

 ## 算法演练

 1. 将每个数字视为 (m) 位二进制字符串，并将 (F_{m-1}(a,b)) 解释为 (\operatorname{LCP}(a,b))。 对于两个整数，LCP 可以通过它们的 XOR 来计算。 如果(x=a\oplus b)非零，则(x)的最高设置位是第一个不同位，因此LCP是(m-\operatorname{bit_length}(x))。 如果(x=0)，则LCP为(m)。 
2.利用local-neighbor属性来降低有效性条件。 对于区间 (i)，涉及前一个区间的唯一约束是

 [
 \运算符名称{LCP}(A_i,L_i)
 \ge
 \运算符名称{LCP}(A_{i-1},L_i),
 ]

 而涉及下一个间隔的唯一约束是

[
 \运算符名称{LCP}(A_i,R_i)
 \ge
 \运算符名称{LCP}(A_{i+1},R_i)。 
]

 每个更远的间隔都会由 LCP 沿着有序整数线的单调性自动处理。 
3.处理完区间(i)后，存储索引为的状态

 [
 (c,b)=
 \左(
 \运算符名称{LCP}(A_i,L_{i+1}),
 \运算符名称{LCP}(A_i,R_i)
 \右）。 
]

 该状态中存储的值是以该状态结束的所有有效选择的乘积之和。 第一个坐标是下一个间隔将用作与 (L_{i+1}) 进行比较的坐标，第二个坐标是下一个间隔将用作与 (R_i) 进行比较的坐标。 
4、在处理一个区间之前，将之前的状态表转化为累积表。 定义

 \sum_{\substack{c\le x\b\ge y}} g[c][b]。 
]

 这正是与具有端点值 (x) 和 (y) 的当前候选兼容的先前代表集。 变换是第一个坐标中的前缀和和第二个坐标中的后缀和，因此需要 (O(m^2))。 
5. 初始化累积表，使得每个第一个代表都被允许。 从概念上讲，这相当于将单个虚拟状态放置在 ((0,m)) 处并应用相同的累积变换。 由于没有先前的间隔，因此必须接受每个可能的第一个候选者。 
6. 对于区间 (i) 中的每个候选 (x)，计算

 [
 A=\operatorname{LCP}(x,L_i),
 ]

 [
 B=\运算符名称{LCP}(x,R_i),
 ]

 [
 C=\operatorname{LCP}(x,L_{i+1})
 ]

 当 (i<N) 时，否则 (C=0)，并且

 [
 D=\运算符名称{LCP}(x,R_{i-1})
 ]

 当(i>1)时，否则(D=0)。 

累积 DP 值 (f[A][D]) 准确包含先前间隔中的兼容选择。 
7. 将先前的贡献乘以当前代表 (x)，因为完整序列的值是所有选定代表的乘积。 将结果添加到状态 ((C,B))：

 [
 克[C][B]
 \mathrel{+}=
 f[A][D]\cdot x。 
]

 所有算术均以模 (100000007) 执行。 
8. 对新构建的 (g) 表应用二维累积变换。 对于下一个间隔，结果表变为 (f)。 
9. 在上一个间隔之后，没有下一个间隔，因此每个最终状态都是有效的。 因此，答案是 (f[m][0])，它包括每个状态，因为它的第一个坐标最多为 (m)，第二个坐标至少为 (0)。 

工作原理：处理间隔 (i) 后，每个 DP 状态准确地代表通过 (i) 的所有有效选择，并按下一个间隔可以观察到的两个 LCP 值进行分类。 当考虑区间 (i+1) 中的候选时，与前一个代表的不等式恰好是 (c\le A) 和 (B\ge D)，并且累积表恰好对这些状态进行求和。 因此，每个有效序列都被传输一次，每个无效转换被排除，并且乘以当前候选序列保持乘积值。 本地邻居引理保证满足这些转换相当于满足与每个代表的原始比较。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 100000007

def lcp(a, b, m):
    x = a ^ b
    if x == 0:
        return m
    return m - x.bit_length()

def cumulative(g, s):
    """Return f[x][y] = sum(g[c][b]) for c <= x and b >= y."""
    f = [row[:] for row in g]

    # Suffix sum in the second coordinate.
    for row in f:
        for k in range(s - 2, -1, -1):
            v = row[k] + row[k + 1]
            if v >= MOD:
                v -= MOD
            row[k] = v

    # Prefix sum in the first coordinate.
    for j in range(1, s):
        row = f[j]
        prev = f[j - 1]
        for k in range(s):
            v = row[k] + prev[k]
            if v >= MOD:
                v -= MOD
            row[k] = v

    return f

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        m, n = map(int, input().split())
        intervals = [tuple(map(int, input().split()))
                     for _ in range(n)]

        s = m + 1

        # Initially every state is reachable for the first interval.
        f = [[1] * s for _ in range(s)]

        # Reuse g between intervals. Only touched entries need clearing.
        g = [[0] * s for _ in range(s)]

        for i, (left, right) in enumerate(intervals):
            touched = []

            next_left = intervals[i + 1][0] if i + 1 < n else 0
            prev_right = intervals[i - 1][1] if i > 0 else 0

            for x in range(left, right + 1):
                a = lcp(x, left, m)
                b = lcp(x, right, m)
                c = lcp(x, next_left, m) if i + 1 < n else 0
                d = lcp(x, prev_right, m) if i > 0 else 0

                value = f[a][d] * x % MOD

                if g[c][b] == 0:
                    touched.append((c, b))

                g[c][b] += value
                if g[c][b] >= MOD:
                    g[c][b] -= MOD

            f = cumulative(g, s)

            for x, y in touched:
                g[x][y] = 0

        out.append(str(f[m][0]))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```这`lcp`函数直接使用 XOR 表示。 如果两个数字不同，则当二进制串从最高有效侧写入时，它们的 XOR 的最高设置位恰好是它们的第一个不同位。 蟒蛇的`bit_length()`在恒定时间内给出该位置，因此每个 LCP 查询成本为 (O(1))，而不是扫描所有 (m) 位。 

DP 表具有从 (0) 到 (m) 的索引，因为 LCP 可以具有该范围内的任何值。 初始表用 1 填充，而不是显式构造虚拟状态 ((0,m)) 并对其进行转换。 它们是等价的：虚拟状态对每个矩形 (c\le A)、(B\ge D) 都有贡献，因此每个初始查询的值为 1。 

对于每个候选人来说，`f[a][d]`是两个相邻约束所需的精确矩形和。 乘以`x`必须在将候选添加到下一个状态之前发生，因为 DP 存储的是乘积之和，而不仅仅是选择的数量。 

这`cumulative`函数首先沿第二个坐标执行后缀和，然后沿第一个坐标执行前缀和。 经过这两关之后，

 [
 f[a][d]=\sum_{c\le a,\b\ge d}g[c][b]。 
]

 顺序很重要，因为第一遍建立 (b\ge d) 条件，而第二遍建立 (c\le a)。 

该实现重用了`g`表并仅清除当前间隔实际触及的状态。 这避免了为每个间隔重复构造和初始化另一个 (O(m^2)) 集合，这在存在许多单例间隔时非常有用。 

Python 整数不会溢出，但所有 DP 值都会按模 (100000007) 减少。 由于每次加法都会合并两个已经低于模数的值，因此一次减法就足够了，而不是使用`%`在内部累积和循环中。

 ## 边缘情况

 对于(m=0)，恰好存在一个可能的整数(0)，并且其二进制表示具有零位。 这`lcp`函数接收`a=b=0`，返回 (m=0)，并且唯一的候选者贡献的因子为零。 因此，DP 返回 (0)，而无需访问负位位置。 

对于单个间隔，没有上一个或下一个代表。 初始 DP 表为每个候选者提供 1 的贡献，而缺失的邻居坐标仅作为虚拟值设置为零。 每个候选都被处理，因此对于 ([0,3])，四个贡献是 (0,1,2,3)，给出 (6)。 

在间隔边界处，必须保持相等。 例如，在示例中，选择 (A_1=1) 和 (A_2=3) 在某些边界比较中给出相等的 LCP，并且该序列仍然有效。 DP 使用`c <= A`和`b >= D`，从来没有严格的不平等，因此关系得以存在。 

区间端点包括在内。 由于间隔形成一个完整的分区，因此 DP 处理的候选总数正好是

 [
 \sum_i(R_i-L_i+1)=2^m。 
]

 这就是为什么迭代`left`通过`right`包容性既是必要的，也是充分的。 

候选者为零的情况也可以自然处理。 它的跃迁贡献乘以零，因此包含该代表的每个完整序列对所请求的乘积和的贡献为零。 这样的状态不需要特殊处理。 

模数异常接近 (10^8)，而不是 (10^9)。 该实现使用精确常量`100000007`，并且 (m=17) 的模测试验证归约是否正确执行。
