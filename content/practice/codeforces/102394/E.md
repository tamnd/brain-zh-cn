 ## 解决方案
 ## 问题理解

 我们从一长串的礼物类型开始。 位置 (i) 最初包含 (g_i)。 我们可以在参赛者之间任意交换礼物，因此最终的数组可以是原始多组礼物类型的任意排列。 

当交换后其位置上的价值与他们最初拥有的价值不同时，参赛者会很高兴。 任务是最大限度地增加此类职位的数量。 

困难在于最终的数组（g=s_n）没有明确给出。 序列可以直接写入最多 (10^6) 个值，也可以通过连接两个先前定义的序列来形成。 一个序列可能会被多次重复使用，所以它的实际长度可以达到(10^{18})。 输入本身比它描述的序列小得多。 

第一个简化是忽略数组的顺序。 假设最常见的礼物类型出现 (M) 次，并且整个数组的长度为 (L)。 如果(M\le L/2)，我们可以安排礼物，让每个位置收到不同的类型，给(L)个快乐的参赛者。 如果 (M>L/2)，则有 (M) 个职位最初持有该主导类型，但只有 (L-M) 个其他类型的天赋可以进入其中。 这些位置中至少 (M-(L-M)=2M-L) 必须保持相同类型。 所有其他位置都可以不同。 因此答案是

 [
 \min(L,2(L-M))。 
]

 等价地，

 [
 \text{答案}=
 \开始{案例}
 L,&2M\le L,\
 2(L-M),&2M>L。 
\结束{案例}
 ]

 因此，整个问题已简化为找到 (s_n) 的两个量：其长度 (L) 和任何礼物类型的最大频率 (M)。 

这些限制使得扩展 (s_n) 变得不可能。 序列定义的数量最多为 (10^6)，所有测试用例中显式列出的值的总数也最多为 (10^6)，但生成的序列可以具有长度 (10^{18})。 即使扩展数组的线性扫描也可能需要 (10^{18}) 次操作。 二次方法很早就被排除了，因为即使 (10^6) 个输入对象也已经使 (10^{12}) 操作变得不可行。 预期的算法必须处理压缩的描述，并花费与输入大小成比例的时间。 

在几种边缘情况下，直接实施可能会默默失败。 

对于单一元素，参赛者不能收到不同的礼物。 例如，```
1
1
1 1 7
```有答案（0）。 假设总是有足够的其他礼物可以移动的公式会错误地声称参赛者可以变得快乐。 

所有的礼物都相同是另一个极端。 为了```
1
1
1 4 5 5 5 5
```答案是（0）。 每个排列都与原始数组相同。 仅检查数组是否包含多个不同值的解决方案是不够的，因为重要的数量是最大频率。 

精确的半频边界也很重要。 为了```
1
1
1 4 1 1 2 2
```每个值出现两次，因此每个位置都可以接收另一个值，答案是（4）。 在错误的方向上使用与 (L/2) 的严格比较可能会错误地让一些参赛者不高兴。 

最后，重复的序列引用必须以其多重性来计数。 考虑```
1
3
1 1 1
2 1 1
2 2 2
```尽管输入中只出现了一次，但最终序列具有 (1) 的 (4) 个副本。 其答案为（0）。 如果实现仅处理每个序列定义一次而不记录最终序列引用它的次数，则会出现此错误。 

## 方法

 蛮力方法很简单。 首先展开每个串联，直到完整的数组 (g) 可用。 然后统计每种礼物类型出现的次数，找到最大频率（M），并使用上面的公式计算出快乐参赛者的最大数量。 

这是正确的，因为交换礼物永远不会改变多重价值观。 一旦我们知道每个值的频率，数组的原始构造就不再重要了。 

问题是扩展数组的大小。 一条链，例如```
1 1 7
2 1 1
2 2 2
2 3 3
...
```每一步都可以加倍长度。 仅经过 60 次串联，长度就已经是 (2^{60})，大于 (10^{18})。 即使输入仅包含几十行，扩展这样的数组也需要大约 (10^{18}) 个元素操作。 

关键的观察是串联只会增加频率。 如果序列 (s_i) 在最终序列中使用一次，则 (s_i) 的每个元素都贡献一次。 如果使用三次，则 (s_i) 的每个元素贡献三倍。 

这给出了将序列定义作为有向无环图的有用解释。 类型 2 序列 (s_i=s_x+s_y) 具有到 (s_x) 和 (s_y) 的边。 从(s_n)开始，我们可以向后传播重数。 令 (w_i) 为整个序列 (s_i) 在扩展 (s_n) 中出现的次数。 最初（w_n=1）。 每当 (s_i=s_x+s_y) 时，每次出现 (s_i) 都会创建一次 (s_x) 和 (s_y)，因此

 [
 w_x\mathrel{+}=w_i,\qquad
 w_y\mathrel{+}=w_i。 
]

 因为每个引用序列都有一个较小的索引，所以处理从 (n) 到 (1) 的索引就足够了。 

当我们到达包含值 (q_1,\ldots,q_k) 的直接指定序列时，每个显式值都会在最终序列中出现 (w_i) 次。 我们可以将 (w_i) 添加到每个值的全局频率中。 总长度可以与(w_i\cdot k)同时累加。 

这将遍历最多 (10^{18}) 个元素的不可能任务转变为仅遍历显式提供的元素和序列定义。 这与参考解决方案中使用的反向标记原理相同。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(L+n)), (L\le 10^{18}) | (O(L+n)), (L\le 10^{18}) | (O(L)) | 太慢了|
 | 最佳 | (O(n+\sum k)) 预期 | (O(n+\sum k)) | 已接受 |

 ## 算法演练

 1. 阅读所有序列定义。 对于直接指定的序列，存储其值。 对于串联，存储两个引用的序列索引。 我们保留定义是因为实际的序列可能是天文数字般大。 
2. 创建重数数组 (w) 并设置 (w_n=1)。 这意味着最终序列当前包含 (s_n) 的一份副本。 
3. 处理从(n)到(1)的序列索引。 如果(w_i=0)，则序列(s_i)对最终答案没有贡献，因此可以跳过。 
4. 如果 (s_i) 是串联 (s_x+s_y)，则将 (w_i) 添加到 (w_x) 和 (w_y)。 (s_i) 的每次出现恰好包含每个子序列的一次出现。 
5. 如果 (s_i) 是具有 (k) 个值的明确列出的序列，则将 (w_i) 添加到每个列出值的频率。 还将 (w_i k) 添加到总长度中。 由于序列仅在其多重性已确定时才被处理，因此每个显式出现都按照它在 (s_n) 中出现的次数进行精确计数。 
6. 跟踪最大全局频率 (M)，同时累加值。 无需重建最终数组。 
7. 处理完所有相关叶子后，令 (L) 为总长度。 如果 (2M\le L)，则回答 (L)。 否则回答(2(L-M))。 第一种情况意味着每个位置都可以接收不同的类型。 在第二种情况下，主导值有太多副本，因此恰好 (2M-L) 个位置被迫保留它。 

### 为什么它有效

 不变量是，在处理序列 (s_i) 之前，(w_i) 等于 (s_i) 在完全扩展的最终序列 (s_n) 中出现的次数。 最初是正确的，因为 (s_n) 出现一次。 对于串联 (s_i=s_x+s_y)，(s_i) 的每次出现都会为每个子项贡献一次出现，因此将 (w_i) 添加到两个子项可以保留不变式。 因此，在叶子处，将每个显式列出的值乘以 (w_i) 就准确地贡献了其在最终序列中出现的真实次数。

所有叶子处理完毕后，（L）和每个礼物频率都是准确的。 当最大频率至多为数组的一半时，不变位置的最小数量为(0)，否则为(2M-L)，因为只有(L-M)个非优势礼物存在占据(M)个优势位置。 因此计算出的答案是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n = int(input())

        kind = bytearray(n + 1)
        left = [0] * (n + 1)
        right = [0] * (n + 1)
        leaves = [None] * (n + 1)

        for i in range(1, n + 1):
            parts = list(map(int, input().split()))

            if parts[0] == 1:
                kind[i] = 1
                k = parts[1]
                leaves[i] = parts[2:]
            else:
                left[i] = parts[1]
                right[i] = parts[2]

        # ways[i] = number of times sequence i occurs in s_n.
        ways = [0] * (n + 1)
        ways[n] = 1

        freq = {}
        total = 0
        maximum = 0

        for i in range(n, 0, -1):
            w = ways[i]
            if w == 0:
                continue

            if kind[i] == 1:
                values = leaves[i]
                total += w * len(values)

                for v in values:
                    nv = freq.get(v, 0) + w
                    freq[v] = nv
                    if nv > maximum:
                        maximum = nv

                # Release the large list as soon as it is no longer needed.
                leaves[i] = None
            else:
                x = left[i]
                y = right[i]
                ways[x] += w
                ways[y] += w

        if maximum * 2 <= total:
            answer = total
        else:
            answer = 2 * (total - maximum)

        out.append(str(answer))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```这`kind`,`left`， 和`right`数组存储压缩的 DAG。`leaves[i]`仅针对直接指定的序列进行填充，因此不会具体化生成的序列。 

这`ways`array 实现从最终序列的反向传播。 从 (n) 到 (1) 的顺序是有效的，因为每个串联仅引用较早的序列。 因此，在算法到达该孩子之前，该孩子会收到其所有贡献。 

字典`freq`存储每种实际礼物类型的频率。 字典是必要的，因为礼物值可以大到 (10^9) 并且不适合直接索引。 频率本身可以大到 (10^{18})，因此 Python 整数在这里很有用。 在 C++ 中，这些数量需要 64 位整数。 官方约束明确允许序列长度最大为 (10^{18})。 

表达式`maximum * 2 <= total`正确处理精确的半边界。 当最大频率正好是总数的一半时，每个位置仍然可以改变。 

叶子的列表在处理后被释放。 这不会改变渐近内存使用量，但会减少反向遍历期间的峰值内存压力。 

## 工作示例

 ### 示例 1

 第一个样本由一个明确给定的序列组成：```
[3, 3, 2, 1, 3]
```反向遍历只有一个节点。 

| 序列 | 多重性| 叶值| 总长度| 最大频率|
 | ---| ---| ---| ---| ---|
 | (s_1) | 1 | 3, 3, 2, 1, 3 | 3, 3, 2, 1, 3 | 5 | 3 |

 礼物类型 (3) 出现 3 次。 由于(2M=6>5)，一个位置被迫保留类型(3)，而其他四个位置可以接收不同的类型。 答案是

 [
 2(5-3)=4。 
]

 这演示了主频率情况。 

### 示例 2

 定义是```
s1 = [3, 3, 2]
s2 = [2, 2, 3, 3]
s3 = s1 + s2
```我们从 (w_3=1) 开始。 

| 处理序列 | 多重性| 行动| 总长度| 最大频率|
 | ---| ---| ---| ---| ---|
 | (s_3) | 1 | (w_1,w_2) | 加 1 0 | 0 |
 | (s_2) | 1 | 添加一个 2 和两个 3 | 4 | 2 |
 | (s_1) | 1 | 添加两个 3 和一个 2 | 7 | 4 |

 最终频率为 (3\mapsto4) 和 (2\mapsto3)。 因此(L=7)和(M=4)。 由于(2M=8>7)，

 [
 \text{答案}=2(7-4)=6。 
]

 该跟踪表明串联本身永远不需要构建。 只有它的多重性才会传播给它的孩子。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(n+\sum k)) 预期 | 每个序列定义都会处理一次，并且每个显式列出的值都会计算一次。 预计会进行字典操作 (O(1))。 |
 | 空间| (O(n+\sum k)) | 存储压缩的序列图、叶值、多重性和频率字典。 |

 在所有测试用例中，(n) 和显式列出的值的总数都以 (10^6) 为界。 因此，即使表示序列的长度接近 (10^{18})，该算法也仅在实际输入大小中执行线性工作。 512 MB 内存限制对于这种表示也足够了。

 ## 边缘情况

 一元情况有 (L=1) 和 (M=1)。 算法对重数为(1)的单叶进行处理，得到`total = 1`和`maximum = 1`，并进入主导分支，因为 (2M>L)。 答案变成(2(1-1)=0)，这与没有其他礼物可用的事实相匹配。 

对于全等输入```
1
1
1 4 5 5 5 5
```唯一的频率是(M=4)，而(L=4)。 该算法计算 (2M=8>4)，因此答案为 (2(4-4)=0)。 任何交换都不能改变任何参赛者的礼物类型。 

对于精确一半输入```
1
1
1 4 1 1 2 2
```频率为 (2) 和 (2)，因此 (L=4) 和 (M=2)。 条件 (2M\le L) 为真，给出答案 (4)。 有效的安排是`[2, 2, 1, 1]`，这不同于`[1, 1, 2, 2]`在每个位置。 

对于占主导地位的情况```
1
1
1 4 1 1 1 2
```类型(1)出现3次，类型(2)出现1次。 只有一种非 (1) 礼物存在，因此三个原始 (1) 位置最多可以改变其中之一。 另外两个必须保留 (1)，正好有两个快乐的参赛者。 该算法获得(L=4)、(M=3)，并返回(2(4-3)=2)。 

对于重复引用，```
1
3
1 1 1
2 1 1
2 2 2
```反向遍历从(w_3=1)开始。 处理(s_3)给出(w_2=2)。 处理(s_2)然后给出(w_1=4)。 显式叶子`[1]`因此计数了四次，因此 (L=M=4)，答案为 (0)。 这正是为什么需要传播多重性而不是简单地访问每个序列一次。 

最后的边缘情况是一个巨大的隐式序列。 一条双链仅使用 61 个定义即可表示一个值的 (2^{60}) 个副本。 该算法从不尝试创建这些副本。 它将多重性向后传播，最终到达权重为 (2^{60}) 的单元素叶子。 Python 的任意精度整数精确地表示该计数，并且由于每个元素具有相同的值，因此最终答案仍然是 (0)。
