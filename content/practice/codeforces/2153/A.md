 ## 解决方案
 ## 问题理解

 我们有一圈苹果树，每棵树上都结着一个具有相关美丽价值的苹果。 您从第一棵树开始，反复绕圈走。 在每棵树上，你都可以选择吃苹果或不吃苹果。 限制是，只有当苹果的美度严格大于你上次吃的苹果的美度时，你才能吃它。 目标是最大化吃掉的苹果总数。 

输入指定多个测试用例。 对于每个测试用例，树的数量$n$连同美丽值列表一起给出$b_1, b_2, \dots, b_n$。 每个测试用例的输出是一个整数：根据规则可以吃掉的苹果的最大数量。 

限制条件适中：$n \le 100$和$t \le 500$。 这意味着$O(n \log n)$甚至$O(n^2)$每个测试用例的解决方案都会顺利运行。 不用担心巨大的输入会迫使渐近最优方法超越简单的排序或线性扫描。 

当所有苹果都具有相同的美感或美感序列严格递减时，就会出现边缘情况。 例如，如果$b = [2,2,2,2]$，只能吃一个苹果。 如果$b = [5,4,3,2,1]$，从任何一棵树开始，每个周期只能吃一个苹果。 对于天真的“如果比上次吃的多的话就吃”的模拟来说，这些情况很棘手，因为最佳策略可能包括完全跳过早期的苹果，以允许稍后吃较小的苹果。 

## 方法

 蛮力方法是模拟每个可能的起点以及每个可能的跳过和吃的顺序。 对于每个周期，您将跟踪最后吃掉的苹果，并尝试是否吃掉或跳过当前苹果的所有组合。 这是有效的，因为它尊重问题的规则，但它是指数级的$n$并变得不可行$n$甚至小至 20 个。 

关键的见解是“美丽必须严格递增”约束意味着除了相对大小之外，吃苹果的顺序无关紧要。 这将问题简化为计算您可以选择的不同美女的最大数量，同时尊重循环顺序。 对美女进行排序并按递增顺序采摘可以保证每个选中的苹果都大于前一个，并且循环性质仅影响第一个采摘。 为了最大化吃掉的苹果，我们总是可以从最小的美丽开始，贪婪地吃掉比上次吃的更大的下一个最小的可用美丽。 

由于圆圈可以任意旋转，因此吃掉的苹果数量由不同美丽值的数量决定，并且我们必须考虑循环中出现的重复值。 因此最大值为$n$如果所有的美女都是独一无二的，并且安排得允许严格按递增顺序吃饭，如果有重复则更小。

 ## 算法演练

 1.读取测试用例的数量。 对于每个测试用例，请阅读$n$以及美女名单$b$。 
2.对美妆清单进行排序。 排序使我们能够轻松地挑选下一个严格大于上次吃过的苹果。 
3. 将计数器初始化为零并初始化变量`last_eaten`为小于任何 apple beauty 的值（例如 0）。 
4. 迭代排序后的美容列表。 对于每一个美，如果它严格大于`last_eaten`，增加计数器并更新`last_eaten`。 
5. 迭代完所有美女后，计数器现在包含可以吃的最大苹果数。 输出这个值。 

为什么有效：通过始终挑选严格大于上次吃掉的最小的可用苹果，我们可以保证最大限度地增加吃掉的苹果数量。 排序后的列表确保每个选择都是有效的，并且计数器捕获总数。 由于围绕圆的相对顺序可以任意跳过，因此循环性质并不限制这种贪婪选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def max_apples(n, beauties):
    beauties.sort()
    count = 0
    last_eaten = 0
    for b in beauties:
        if b > last_eaten:
            count += 1
            last_eaten = b
    return count

t = int(input())
for _ in range(t):
    n = int(input())
    beauties = list(map(int, input().split()))
    print(max_apples(n, beauties))
```该解决方案读取每个测试用例，对美女进行排序，并贪婪地计算可以吃掉的苹果数量。 排序对于保证严格的递增顺序至关重要。 我们使用一个简单的计数器和一个跟踪变量来记录最后吃掉的美女。 该逻辑通过跳过任何不严格大于前一个的苹果来正确处理重复项。

 ## 边缘情况

 对于一棵树$n=1$对于 beauty 1，算法正确地计算出 1 个苹果。 当所有的苹果都有着同样的美丽，比如$b = [3,3,3]$，只计算第一个苹果； 随后的苹果将被忽略，因为它们并不是严格意义上的更大。 对于具有重复项的序列，算法会跳过重复值，直到出现严格更大的美丽值，从而正确地最大化总吃量。 循环排序不会影响计数，因为贪婪排序选择已经保证了消费的最优顺序。
