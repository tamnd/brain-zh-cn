 ## 解决方案
 ## 问题理解

 我们得到一个数组`a`长度`n`它满足一个称为“可爱”的特殊属性，它可以防止四个索引的某些重复模式。 就这个问题而言，“可爱”的确切定义并不重要，重要的是它的后果：它保证子数组中任何数字的频率的行为方式使我们能够有效地计算出现奇数次的数字的总和。 

任务是处理`q`查询。 每个查询都要求获取连续子数组的“美丽”`a`，其中美丽是在该子数组中出现奇数次的不同数字的总和。 查询被编码：每个查询的索引取决于先前的答案，这强制使用在线算法，而不是提前预先计算所有查询的答案。 

限制很严格。 总和`n`和`q`所有测试用例的最大可达`5 * 10^5`，因此独立计算每个查询频率的暴力方法将涉及最多`O(n*q)`操作，在最坏的情况下高达 ~2.5 * 10^11，显然太大了。 我们需要更接近的东西`O(n + q)`或者`O((n + q) log n)`每个测试用例。 

不明显的边缘情况出现在所有元素都相同或所有元素出现偶数次的子数组中。 例如，一个数组`[3,3,3]`长度为 3 的整个数组的美度总是为 3，但是`[3,3,3,3]`产生 0，因为所有计数都是偶数。 任何将所有元素相加或假设非零美的幼稚尝试都会失败。 

## 方法

 暴力解决方案将迭代每个查询，计算子数组中每个元素的频率，并对出现奇数次的值求和。 这适用于小型`n`和`q`，但与`n`和`q`最多`5 * 10^5`，每个查询可能需要 O(n) 次操作，从而导致`O(n*q)`整体复杂性。 

关键的见解是该数组很“可爱”，这意味着在四元素模式中没有数字与另一个数字重复交替。 更深层次的结果是，在任何子数组中，每个数字最多出现在一个连续的块中。 换句话说，数字出现的位置是连续的。 这意味着子数组中数字的奇偶校验仅当子数组在其块内开始或结束时才会改变。 因此，我们可以将每个值的出现视为一个二进制标志：如果某个值在子数组中出现奇数次，则它有助于美观，否则则没有。 当我们扩展或缩小子阵列时，更新美感就变成了根据频率奇偶性切换贡献的问题，这允许使用类似位掩码的滑动窗口方法。 

我们可以使用两指针或 Mo 算法方法有效地实现这一点。 由于查询端点取决于先前的答案，因此我们必须按顺序处理查询。 我们维护一个频率数组和具有奇数频率的数字的运行总和。 当移动左端点或右端点时，我们增加或减少相应元素的频率并相应地调整美感。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n*q) | O(n*q) | O(n) | 太慢了 |
 | 滑动窗口/在线奇偶校验跟踪| O(n + q) | O(n) | 已接受 |

 ## 算法演练

 1.初始化频率数组`freq`长度`n+1`为零。 这将跟踪每个数字在当前子数组中出现的次数。 初始化`beauty`为零。 
2. 对于每个查询，解码端点`l`和`r`使用前面的答案，应用给定的模公式并取`min`和`max`正确订购它们。 
3. 将当前子数组的右端点从之前的位置扩展到新的位置`r`。 对于添加的每个元素，增加其频率`freq`。 如果新的频率是奇数，则将该元素添加到`beauty`。 如果它变成偶数，则减去它`beauty`。 这种切换捕获了奇偶校验效应。 
4.同样，将左端点调整为新的`l`。 如果左端点向右移动，则减少被删除元素的频率，更新`beauty`以相同的基于奇偶校验的方式。 如果它向左移动，则增加频率并更新`beauty`。 
5. 将两个端点对齐后`[l, r]`，记录当前`beauty`作为此查询的答案。 该值将用于解码下一个查询。 
6. 对测试用例中的所有查询重复此操作。 

为什么它有效：“可爱”属性保证每个值都出现在连续的块中。 因此，增加或减少子数组端点只会切换边界处值的频率奇偶性。 通过维护具有奇数计数的值的运行总和，我们可以更新`beauty`每个添加或删除的元素在恒定时间内递增。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def process_test_case():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    queries = [tuple(map(int, input().split())) for _ in range(q)]
    freq = [0] * (n + 1)
    beauty = 0
    ans_prev = 0
    l_curr = 0
    r_curr = -1
    res = []

    for x_raw, y_raw in queries:
        x = ((x_raw - 1 + ans_prev) % n)
        y = ((y_raw - 1 + ans_prev) % n)
        l = min(x, y)
        r = max(x, y)

        while r_curr < r:
            r_curr += 1
            val = a[r_curr]
            freq[val] += 1
            if freq[val] % 2 == 1:
                beauty += val
            else:
                beauty -= val

        while r_curr > r:
            val = a[r_curr]
            freq[val] -= 1
            if freq[val] % 2 == 1:
                beauty += val
            else:
                beauty -= val
            r_curr -= 1

        while l_curr < l:
            val = a[l_curr]
            freq[val] -= 1
            if freq[val] % 2 == 1:
                beauty += val
            else:
                beauty -= val
            l_curr += 1

        while l_curr > l:
            l_curr -= 1
            val = a[l_curr]
            freq[val] += 1
            if freq[val] % 2 == 1:
                beauty += val
            else:
                beauty -= val

        res.append(beauty)
        ans_prev = beauty

    print(*res)

def main():
    t = int(input())
    for _ in range(t):
        process_test_case()

if __name__ == "__main__":
    main()
```该代码初始化频率跟踪并通过增量移动端点来处理每个查询。 计数的奇偶性决定了数字是否有助于美。 解码查询使用前面的答案来正确计算模位置，尊重问题的在线性质。 边界调整确保没有相差一的错误，并且每个查询都按顺序处理。 

## 工作示例

 ### 示例 1：具有混合频率的子数组

 输入子数组：`[3, 2, 2, 1]`。 初始美感为0。 

| 步骤| 行动| 频率 | 美丽|
 | --- | --- | --- | --- |
 | 添加 3 | 频率[3]=1 | 3:1 | 3 |
 | 添加 2 | 频率[2]=1 | 2:1,3:1 | 5 |
 | 添加 2 | 频率[2]=2 | 2:2,3:1 | 3 |
 | 添加 1 | 频率[1]=1 | 1:1,2:2,3:1 | 4 |

 Beauty 4 符合预期输出。 这表明增量更新正确处理从奇数到偶数的切换。

 子数组`[3,3,3,3]`。 

| 步骤| 行动| 频率 | 美丽|
 | --- | --- | --- | --- |
 | 添加 3 | 频率[3]=1 | 3:1 | 3 |

 | 添加 3 | 频率[3]=3 | 3:3 | 3 |

 这证实了即使计数超过 2，切换也能正常工作。
