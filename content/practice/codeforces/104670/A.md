 ## 解决方案
 ## 问题理解

 我们得到了一系列每日测量值，其中每一天都有一个整数值。 对于每一天 i，我们都希望将这一天与任何较早的一天 j（包括其本身）进行比较，并计算在惩罚时间距离后这两天之间的测量“有意义的跳跃”有多大。 

两天之间的分数定义为测量值的绝对差值减去与日期相距多远成正比的罚分。 形式上，对于每个 i，我们考虑所有 j ≤ i 并评估 |xi − xj| − c·(i − j)，然后取最大值。 

输出是一个数组，其中第 i 个值是第 i 天的最高分数。 

约束 n 高达 4 · 10^5 立即排除所有天对之间的任何二次比较。 简单的 O(n^2) 方法需要大约 10^11 次操作，这远远超出了几秒钟内任何可行的限制。 这促使我们寻求一种解决方案，其中每个索引在恒定或对数时间内做出贡献，通常通过前缀维护技巧或将表达式转换为我们可以通过运行摘要进行优化的转换。 

当所有值都相同时，会出现微妙的边缘情况。 在这种情况下，每个差异 |xi − xj| 为零，并且所有 i 的答案都应该为零。 任何忘记将 j = i 作为有效选择的方法都会错误地产生负值或无法钳位为零。 

当最佳较早索引在时间上非常接近但具有稍差的值，而较远的索引具有更好的值时，会发生另一种极端情况。 这正是天真的“跟踪最后的最大值或最小值”策略失败的原因，因为时间损失与值差异相互作用，并且如果不进行转换就无法分离。 

## 方法

 暴力法很简单。 对于每一天 i，迭代之前的所有天 j 并直接计算分数，保留最好的。 这是正确的，因为它明确地评估每个候选对。 然而，每个 i 最多扫描 i 个值，因此操作总数以 1 + 2 + … + n 的形式增长，大约为 n^2 / 2。当 n = 4 · 10^5 时，这变得完全不可行。 

关键的观察结果是，绝对值根据 xi 是否大于 xj 将问题分为两种线性形式。 每种形式都可以重新排列，以便将所有对 j 的依赖隔离到一个前缀统计量中，而对 i 的所有依赖都是我们每个索引计算一次的简单表达式。 

展开表达式给出两种情况。 如果我们去掉绝对值，我们就得到 xi − xj 或 xj − xi。 一旦我们扩大时间惩罚 c·(i − j)，它们中的每一个都在 i 和 j 中变成线性。 这让我们可以将问题重写为在所有先前的 j 上维护两个运行量：一个跟踪 xj − c · j 的最小值，一个跟踪 xj + c · j 的最大值。 

这将每个查询减少到恒定时间，因为在第 i 天，我们仅将 xi 与这两个前缀摘要结合起来。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从左到右处理数组，维护有关所有先前索引的信息。

1. 扫描时保持两个运行值：到目前为止看到的所有 j 的 xj − c·j 的最小值和 xj + c·j 的最大值。 这些以与绝对值的两个可能方向一致的方式总结了所有先前的选择。 
2. 对于每个索引 i，计算两个候选答案。 第一个候选对应于xi大于xj的情况，变成(xi - c·i) - min(xj - c·j)。 这衡量了 xi 相对于之前看到的最佳“低调整值”的大小。 
3、第二个候选对应xj大于xi的情况，则变为max(xj+c·j)−(xi+c·i)。 这衡量了先前的高调整值与当前调整值相比有多大。 
4. 第 i 天的答案是这两个候选者中的最大值。 计算后，我们用当前索引 i 更新两个运行摘要，以便将来可用。 

### 为什么它有效

 该转换将对 j 的依赖性隔离为前缀上的两个单调统计量。 每个可能的较早索引都会对两种线性形式之一做出贡献，并且前缀最小值或最大值可确保始终在 O(1) 时间内表示最佳可能的 j。 由于通过这些摘要隐式地考虑了每一对 (i, j)，因此计算出的最大值与暴力定义完全匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, c = map(int, input().split())
    x = list(map(int, input().split()))

    INF = 10**30

    min_left = INF
    max_left = -INF

    res = []

    for i in range(n):
        xi = x[i]

        val1 = xi - c * i
        val2 = xi + c * i

        if i == 0:
            res.append(0)
        else:
            best1 = val1 - min_left
            best2 = max_left - val2
            res.append(max(best1, best2))

        expr1 = xi - c * i
        expr2 = xi + c * i

        if expr1 < min_left:
            min_left = expr1
        if expr2 > max_left:
            max_left = expr2

    print(*res)

if __name__ == "__main__":
    solve()
```该实现保留两个运行值，它们直接对应于演练中导出的代数形式。 变量`min_left`存储迄今为止看到的 xj − c·j 的最小值，而`max_left`存储 xj + c·j 的最大值。 在每一步中，我们都会在恒定时间内计算当前指数对两个摘要的贡献。 

一个常见的错误是在计算 i 的答案之前更新前缀值，这会错误地允许 j = i 以破坏预期分离的方式影响自身。 正确的顺序是首先计算答案，然后将当前索引合并到运行结构中。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, c = map(int, input().split())
    x = list(map(int, input().split()))

    INF = 10**30
    min_left = INF
    max_left = -INF
    res = []

    for i in range(n):
        xi = x[i]
        if i == 0:
            res.append(0)
        else:
            best1 = (xi - c * i) - min_left
            best2 = max_left - (xi + c * i)
            res.append(max(best1, best2))

        min_left = min(min_left, xi - c * i)
        max_left = max(max_left, xi + c * i)

    return " ".join(map(str, res))

# provided sample
assert run("5 1\n2 7 1 5 4\n") == "0 4 5 3 1"

# minimum size
assert run("1 10\n5\n") == "0"

# all equal
assert run("4 3\n7 7 7 7\n") == "0 0 0 0"

# increasing values
assert run("5 1\n1 2 3 4 5\n") == "0 0 0 0 0"

# strong jump late
assert run("4 2\n10 1 1 50\n") == "0 7 7 42"

 ## 边缘情况

 当所有值相同时，变换量 xj − c·j 和 xj + c·j 仅由于线性惩罚项而演化。 该算法仍然保持正确的最小值和最大值，但两个候选表达式在每一步都会崩溃为零，因为 xi 匹配每个 xj 并且惩罚永远不会产生正增益。 这与零数组的预期输出匹配。 

当最佳先前索引在时间上很远时，前缀统计信息已经对该索引进行编码，无论它有多远。 例如，如果一个非常大的值较早出现，则其贡献仍存储在 max(xj + c·j) 中，并继续正确影响所有未来索引，因为线性调整精确地补偿了时间距离。
