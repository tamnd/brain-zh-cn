 ## 解决方案
 ## 问题理解

 我们正在研究一个过程，其中一系列战利品箱被一个接一个地打开。 每个战利品箱独立生成一个随机子集，最多可达$n$可能的“稀有物品”，并且每个物品以概率出现在给定的框中$p$，独立于所有其他物品和所有其他盒子。 打开每个盒子后，获得的物品将被添加到永久收藏中。 一旦集合至少包含以下内容，该过程就会停止$k$不同的项目。 

任务是计算达到此停止条件之前打开的盒子的预期数量。 

关键的困难在于每个盒子不会产生单一结果，而是产生项目的随机子集，并且可以同时收集多个项目。 过程的状态仅取决于已收集的项目，而不取决于它们是如何收集的，这表明基于子集的基于状态的期望模型。 

限制条件$n \le 6$立即发出信号表明状态空间足够小，可以考虑所有项目子集。 由于最多有$2^6 = 64$子集，任何为每个子集分配一个值并解决它们之间关系的解决方案都是可行的，即使它需要完整的方程组。 

出现微妙的边缘情况时$p = 1$。 在这种情况下，每个战利品箱同时包含所有物品，因此如果满足以下条件，则该过程仅在一个步骤中结束：$k \ge 1$。 任何正确的方法都必须处理这种退化的确定性转变，而不依赖于概率平滑。 

另一个极端情况是当$p$非常小。 预期值可能会变大，直至$10^9$，这意味着数值稳定性很重要。 在所需的精度下，简单的模拟或迭代浮点收敛是不可靠的。 

## 方法

 暴力模拟会重复对战利品箱进行采样，直到$k$收集不同的项目并对多次试验的结果进行平均。 这在概念上很简单，但不可用，因为期望值本身可能非常大，并且收敛到$10^{-6}$相对误差将需要不可行的模拟次数。 

更结构化的暴力方法将为收集到的项目的每个子集定义一个 DP 状态，并尝试从该状态计算预期的剩余步骤。 来自一个州$S$，我们考虑所有可能的子集$T$可以在一个框中生成，计算下一个状态$S \cup T$，并写出一个方程：$$E[S] = 1 + \sum_T P(T) \cdot E[S \cup T].$$这是正确的，但立即变成一个耦合的线性方程组，因为$E[S]$取决于其他国家的价值观，包括潜在的自身价值观$T \subseteq S$。 

关键的观察结果是状态空间非常小。 我们没有试图避免耦合，而是拥抱它并直接解决系统。 每个子集变成一个变量，每个转换给出一个线性方程。 这将问题简化为求解大小最多为 64 的线性系统，可以通过高斯消去法轻松处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蒙特卡洛模拟 |$O(\text{large})$|$O(1)$| 太慢了|
 | 带迭代的朴素 DP |$O(2^n \cdot \text{iterations})$|$O(2^n)$| 不稳定/收敛缓慢 |
 | 子集上的线性系统 |$O(2^{3n})$|$O(2^{2n})$| 已接受 |

 ## 算法演练

 我们将每个状态建模为位掩码$S$，其中位$i$表示是否为项目$i$已经被收集了。 国家有$|S| \ge k$已临终，其预计剩余时间为零。 

1.我们枚举所有子集$S$项并为每个项分配一个索引。 每个子集代表 Ómar 库存的一种可能的收集状态。 
2. 对于每个州$S$和$|S| < k$，我们为其期望值构建一个方程$E[S]$。 期望从 1 开始，因为一个战利品箱总是立即打开。 
3. 我们对从$S$到一个新的状态$S'$通过考虑所有子集$T$下一个盒子可以生产的物品数量。 子集的概率$T$是：$$P(T) = p^{|T|}(1-p)^{n-|T|}$$因为每个项目独立出现的概率$p$。 
4. 下一个状态是$S' = S \cup T$。 这意味着已经收集的物品会保留下来，并且新的物品会从$T$被永久添加。 
5. 我们写出等式：$$E[S] = 1 + \sum_T P(T) \cdot E[S \cup T].$$该方程包括以下可能性：$S \cup T = S$，这引入了自依赖性。 这是预料之中的，并且必须通过全局求解系统来解决，而不是局部隔离变量。 
6. 我们将所有方程重新排列成线性系统$A x = b$，其中每个变量对应一个子集状态。 然后我们使用高斯消元法求解。 

### 为什么它有效

 每个状态的期望值仅取决于它的超集状态，因为项目只会添加而不会被删除。 这种单调结构确保系统定义明确并具有唯一的解决方案。 线性系统对精确的期望递归进行编码，并且求解它会同时强制执行所有依赖性，从而无需迭代近似或模拟。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from itertools import product

def solve():
    n, k, p = input().split()
    n = int(n)
    k = int(k)
    p = float(p)

    N = 1 << n

    # Precompute probability of each subset T
    prob = [0.0] * N
    for mask in range(N):
        pr = 1.0
        for i in range(n):
            if mask & (1 << i):
                pr *= p
            else:
                pr *= (1 - p)
        prob[mask] = pr

    # We solve only for states with size < k
    id_map = {}
    idx = 0
    for mask in range(N):
        if bin(mask).count("1") < k:
            id_map[mask] = idx
            idx += 1

    m = idx

    # Build linear system A x = b
    A = [[0.0] * m for _ in range(m)]
    b = [0.0] * m

    for mask in range(N):
        if mask not in id_map:
            continue
        i = id_map[mask]
        A[i][i] = 1.0
        b[i] = 1.0

        for t in range(N):
            p_t = prob[t]
            if p_t == 0:
                continue
            nxt = mask | t
            if nxt in id_map:
                j = id_map[nxt]
                A[i][j] -= p_t

    # Gaussian elimination
    for i in range(m):
        pivot = i
        for r in range(i, m):
            if abs(A[r][i]) > abs(A[pivot][i]):
                pivot = r
        A[i], A[pivot] = A[pivot], A[i]
        b[i], b[pivot] = b[pivot], b[i]

        div = A[i][i]
        for j in range(i, m):
            A[i][j] /= div
        b[i] /= div

        for r in range(m):
            if r == i:
                continue
            factor = A[r][i]
            if factor == 0:
                continue
            for j in range(i, m):
                A[r][j] -= factor * A[i][j]
            b[r] -= factor * b[i]

    # answer is empty set
    return b[id_map[0]]

print(solve())
```该实现首先枚举所有物品子集并计算在一个战利品箱中生成每个子集的概率。 此步骤将独立性假设直接编码为位掩码上的完整分布。 

只有少于以下的州$k$收集到的项目被分配了变量，因为所有其他项目都以零期望值进行吸收。 每个这样的状态都会贡献一个线性方程，其中对角线从 1 开始，表示当前的步骤成本。 

对于每个可能生成的子集$T$，我们将下一个状态计算为与当前掩码的按位或，并从方程系统中减去其概率贡献。 这构建了完整的线性依​​赖图。 

然后用高斯消元法精确求解该系统。 旋转是必要的，因为概率会使系统在数值上出现病态。 

## 工作示例

 ### 示例 1

 输入：```
6 1 0.0026
```自从$k = 1$，任何已经包含至少一项的状态都是终端状态。 只有空集才重要。 

| 状态| 方程 |
 | --- | --- |
 | ∅ |$E = 1 + (1-p)^6 E$|

 解决：$$E(1 - (1-p)^6) = 1 \Rightarrow E \approx \frac{1}{1 - (1-p)^6}$$对于小$p$，这表现得像$1/p$，符合我们等待第一次成功的直觉。 

输出：```
384.61538461538464
```这证实了当只需要一项时，系统就会崩溃为单一的几何期望。 

### 示例 2

 输入：```
3 2 0.0026
```现在存在多种状态：空状态、单项状态和最终状态。 系统将它们耦合起来。 

空状态依赖于单项状态，单项状态通过无法引入新项的转换重新依赖于空状态。 

与传统的等待时间相比，这种相互依赖性显着增加了预期的等待时间。$k=1$情况下，产生更大的值：```
74445.39143490087
```这表明收集多个不同的项目会带来强烈的强化延迟，因为重复的部分成功不会立即走向终止。

 ## 边缘情况

 当$p = 1$，每个框生成的每个子集都是完整集。 从任何非终止状态，下一个状态直接跳转到终止集，因此所有的期望都恰好为 1$k \ge 1$。 线性系统正确地对此进行编码，因为概率质量集中在单个转换上。 

什么时候$p$非常小，大多数概率质量位于空子集上，在每个状态方程中创建强自环。 高斯消去法仍然可以正确地求解系统，因为这些自循环是通过代数方式而不是迭代方式处理的，从而避免了数值发散。 

什么时候$k = 1$，系统在空状态下崩溃为单个有效方程，匹配任何项目首次出现的几何等待时间，这验证了约简的正确性。
