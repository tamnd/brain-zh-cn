 ## 解决方案
 ## 问题理解

 我们得到了一个固定的小结标识符宇宙，编号从 1 到 1000。`n`她必须学习独特的结。 她已经学会了`n-1`其中，也以清单的形式给出，而她所学到的知识中恰恰缺少一个必需的结。 

任务是识别单个缺失的数字，并确保每个学习的结都保证是原始所需集合的一部分。 

约束条件非常小，有`n`最大为 50，值最大为 1000。这立即告诉我们，即使非常简单的方法也足够了。 任何在线性或接近线性时间内运行的解决方案`n`将是瞬时的。 即使超过 50 个元素的二次或嵌套扫描仍然可以忽略不计。 

不存在棘手的隐藏约束，例如重复或丢失多个值。 两个列表都明确声明包含不同的值，因此我们不需要处理多重性或频率模糊性。 

主要的边缘情况是结构性的而不是计算性的。 由于缺失值保证存在并且是唯一的，因此任何方法都必须保留精确的隶属推理。 一个幼稚的错误是假设两个列表之间的顺序或对齐。 例如，如果尝试比较位置而不是集合成员资格，则结果将失败，因为输入的顺序是任意的。 

第二个微妙的边缘情况是忘记丢失的元素始终来自第一个列表。 如果有人错误地计算对称差或与 1 到 1000 的整个范围进行比较，他们可能会意外地选择与输入约束无关的数字。 

简单位置比较失败的示例：

 输入：```
4
1 2 3 4
4 2 3
```正确输出：```
1
```如果一个人错误地按索引对齐进行减去（仅比较第一个元素），他们会错误地认为`1`与`4`不匹配意味着一些不相关的事情。 

## 方法

 蛮力的想法很简单：对于所需列表中的每个结，扫描学习的列表并检查它是否出现。 如果我们找到一个没有出现在学习列表中的所需结，那就是答案。 

这是有效的，因为成员资格是定义正确性的唯一条件。 然而，对于每个`n`所需的结，扫描学习的列表成本`O(n)`，导致`O(n^2)`解决方案。 和`n ≤ 50`，这在实践中仍然完全没问题，但对于这样一个简单的结构来说，从概念上来说这是不必要的开销。 

更清晰的观察是，我们正在比较两个仅相差一个元素的集合。 我们可以使用算术来汇总差异，而不是重复进行成员资格检查。 由于所有值都是整数，因此我们可以对所有所需的结求和并减去学习的结的总和。 结果正是缺失值。 

这是有效的，因为在减去两个和时，每个公共元素都会抵消，只留下缺失的项。 

另一个等效的观点是使用 XOR。 将所有必需值与所有学习值进行异或也会取消重复项，留下缺失值。 两种方法都依赖于相同的取消属性，但求和更简单且更直接可读。 

基于总和的方法将问题简化为对两个列表进行单次传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（会员扫描）| O(n²) | O(1) | O(1) | 已接受 |
 | 求和或异或取消 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`n`，然后阅读所需结列表和已学结列表。 我们将两者保留为简单的整数数组。 
2. 计算所有所需节数的总和。 这代表应该存在的总“质量”。 
3. 计算所有学习结的总和。 这代表了索尼娅已经拥有的东西。 
4. 从所需的总和中减去学习的总和。 不同之处在于缺少结，因为所有共享元素都取消一次。 
5. 输出结果值。 

减法工作顺利的原因是，两个列表中出现的每个结对两个总和的贡献相等，因此它在差异中消失。 只有一个缺失的元素仍然未配对。 

### 为什么它有效

 我们有效地利用了这样一个事实：整数的加法是结合性和交换性的，因此顺序并不重要。 如果我们将所需的集合写为`A`并学习设置为`B`，我们知道`B`正是`A`没有一个元素`x`， 然后：`sum(A) = sum(B) + x`重新排列给出`x = sum(A) - sum(B)`。 输入的其他结构不会影响该恒等式，因此计算出的值必须正是丢失的结。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input().strip())
    required = list(map(int, input().split()))
    learned = list(map(int, input().split()))

    total_required = sum(required)
    total_learned = sum(learned)

    print(total_required - total_learned)

if __name__ == "__main__":
    main()
```该解决方案分为三个逻辑部分：输入解析、聚合和输出。 关键的实现细节是确保两个列表都作为整数完全使用。 由于约束很小，因此不需要流式或增量更新。 

一个常见的错误是忘记在求和之前将输入字符串转换为整数，这会导致在某些语言中进行字符串连接而不是算术加法。 在Python中，`map(int, ...)`完全避免了这个问题。 

另一个微妙的问题是假设两个列表都已排序或对齐，但事实并非如此。 该算法有意避免对排序的任何依赖。

 ## 边缘情况

 一种边缘情况是最小的有效情况`n = 2`，其中恰好缺少一个值。 例如：

 输入：```
2
5 7
7
```所需的总和为 12，学习的总和为 7，因此输出为 5。算法仍然正确运行，因为减法不依赖于列表大小。 

另一种情况是当值接近允许范围的边界时，例如 1 和 1000。例如：

 输入：```
3
1 1000 500
1000 500
```所需的总和为 1501，学习的总和为 1500，生成 1。即使是极端值也不会影响正确性，因为不涉及溢出或排序假设。 

最终的结构边缘情况是缺失值是集合中最大或最小的情况。 由于该算法不依赖于排序或索引，因此它会统一处理所有位置，因此丢失的极值的处理方式与任何其他元素相同。
