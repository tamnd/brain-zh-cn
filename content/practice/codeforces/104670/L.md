 ## 解决方案
 ## 问题理解

 每条输入行描述一对周期性事件。 对于给定的一对，两个物种每隔固定的年数就会重新出现，我们被告知去年它们一起出现。 根据这些信息，我们想要预测同一对下一次出现在一起的时间。 

因此，对于由最后一个同时发生的年份和两个周期长度组成的每个三元组，我们实际上是在数轴上查看重复模式：从那一年开始，一个事件每重复一次`c1`年和其他每隔`c2`年。 每当两个周期再次对齐时，该对就会重合。 

任务是计算每对的下一个这样的重合年份，然后选择所有对中最早的一个。 

约束足够小，我们可以直接计算每对的答案，而不需要超出基本算术的优化技巧。 由于最多有 99 对且循环长度低于 100，即使在恒定时间内对每对进行直接计算也是微不足道的。 

这里可能出现的一个天真的错误是假设下一个同时出现的只是`y + max(c1, c2)`。 但这会失败，因为对齐同时取决于两个周期，而不仅仅是较慢的周期。 

例如，如果`y = 2000`,`c1 = 6`,`c2 = 4`，然后加上 6 得到 2006，但从基本对齐来看 2006 不能被 4 整除，因此它不是有效的同时出现。 正确的下一个重合由最小公倍数确定。 

另一个微妙的问题是忘记了我们被要求提供_所有对中的第一年_，而不是独立的第一对。 每对都会产生一个候选年份，只有在计算完所有候选年份后我们才会对它们进行比较。 

## 方法

 解决问题的直接方法是从`y + 1`，检查每个候选年份是否与两个周期匹配。 对于给定的对，这意味着反复检查是否`(year - y) % c1 == 0`和`(year - y) % c2 == 0`。 由于周期最多为 99 个，因此最多可以保证下一场比赛`lcm(c1, c2)`步骤，以 9801 为界。最多 99 对，这种方法仍然可以接受，但它是不必要的间接。 

更清晰的观察来自于理解“两个周期再次对齐”的结构含义。 一旦两个周期序列在一年重合`y`，它们每次都会再次重合`lcm(c1, c2)`年。 这消除了任何模拟的需要。 下一次出现的情况固定为`y + lcm(c1, c2)`。 

这将任务减少为计算每对一个算术值并取最小值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(k·lcm(c1,c2)) | O(k·lcm(c1,c2)) | O(1) | O(1) | 已接受但没有必要 |
 | LCM直接计算| O(k log min(c1,c2)) | O(k log min(c1,c2)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每一对，读取最后同时发生的年份`y`和周期长度`c1`,`c2`。 这定义了一个重复对齐问题，锚定于`y`。 
2. 计算最大公约数`c1`和`c2`，然后使用导出最小公倍数`lcm = (c1 // gcd) * c2`。 这给出了两个周期再次对齐的确切时间段。 
3. 计算该对的下一个出现年份：`y + lcm`。 
4. 跟踪所有对的所有计算的下一个出现年份的最小值，因为该问题要求所有物种对之间最早的未来重合。 

### 为什么它有效

 一旦两个周期过程在某个时间点对齐，它们未来的对齐就会形成一个严格的周期序列，由它们各自周期的最小公倍数控制。 任何早于`lcm(c1, c2)`将与最小公倍数的定义相矛盾，因为它意味着更小的共享周期。 因此，每一对明年都会贡献一个候选者，并且选择跨对中的最小值可以保持全局正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import math

def solve():
    k = int(input())
    ans = 10**30

    for _ in range(k):
        y, c1, c2 = map(int, input().split())
        g = math.gcd(c1, c2)
        lcm = (c1 // g) * c2
        ans = min(ans, y + lcm)

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案读取每个三元组并立即将其转换为确定的未来事件年。 关键的实现细节是在乘法之前使用整数安全除法来计算最小公倍数，这样即使在值接近上限时也可以防止溢出并保持正确性。 

最终答案是增量维护的，避免存储所有候选答案。 

## 工作示例

 考虑输入：```

1992 14 18
```对于第一对，我们计算`lcm(13, 17) = 221`，所以明年是`1992 + 221 = 2213`。 

对于第二对，`lcm(14, 18) = 126`，所以明年是`1992 + 126 = 2118`。

```这里`gcd(5,7)=1`， 所以`lcm=35`下一个出现的是`2036`。 没有竞争对，所以这是最终答案。

 ## 边缘情况

 当两个周期长度相同时，会出现第一种边缘情况。 对于像这样的输入`2021 10 10`，gcd 等于数字本身，因此 lcm 折叠为 10。该算法正确地生成`2021 + 10`，并且不需要特殊处理，因为该公式自然可以处理这种情况。 

另一种情况是一个周期除另一个周期时，例如`2010 4 12`。 这里的 gcd 是 4，所以 lcm 变成 12，而不是 16。不除以 gcd 的简单乘法方法会高估周期并产生不正确的后续年份，而实施的公式避免了重复计算共享因子。 

最后的边缘情况是当多个对产生非常接近的候选年份时。 由于我们只跟踪运行最小值，因此该算法可以正确处理联系和排序，而不需要对中间结果进行排序或存储。
