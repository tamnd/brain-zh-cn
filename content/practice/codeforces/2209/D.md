 ## 解决方案
 ## 问题理解

 该问题要求我们构造一系列三种颜色的鬼火：红色、绿色和蓝色。 OtterZ 每种颜色的数量有限，表示为$r$,$g$， 和$b$。 目标是连续放置尽可能多的鬼火，同时避免两个约束。 首先，相邻的两个鬼火不能具有相同的颜色。 其次，相距三个位置（即正好被另外两个鬼火隔开）的两个鬼火不能具有相同的颜色。 本质上，该序列必须避免在距离 1 和距离 3 处重复。 

每个测试用例指定三种颜色的计数，并且一次运行处理多个测试用例。 因为所有测试用例的鬼火总数不超过$10^6$，我们必须确保算法相对于每个测试用例的鬼火数量大致以线性时间运行。 这排除了任何尝试枚举所有排列或天真地检查每个可能位置的方法，这可能会花费鬼火数量的阶乘时间。 

当一种或多种颜色为零时，就会出现边缘情况。 例如，如果$r = 0, g = 3, b = 0$，我们只能放置绿色鬼火。 正确的顺序是“G”，因为两个相邻的果岭会违反邻接规则。 类似地，当计数相等时，可能存在多个交织序列，并且算法必须在不违反约束的情况下选择一个序列。 忽略距离 3 规则会导致长度超过 3 的序列出现微妙的失败。 

## 方法

 蛮力方法是尝试鬼火的每一种排列，并测试所得序列是否满足这两个约束。 对于测试用例$n = r + g + b$， 有$O(n!)$排列。 即使对于较小的值，这显然也是不可行的$n$， 鉴于$n$可以达到$10^6$跨所有测试用例。 

贪婪策略之所以有效，是因为问题具有重复的局部结构：唯一的限制涉及相距一步和三步的位置。 在每一步中，算法都可以选择具有最大剩余计数且不违反邻接和距离 3 约束的颜色。 关键的见解是，维护最后三个放置的鬼火的简单历史足以在每一步做出正确的选择。 一旦使用某种颜色，其数量就会减少。 如果某个位置没有有效颜色，则序列终止，确保构建最大长度序列。 

这种贪婪方法之所以有效，是因为约束仅涉及局部交互。 除了最后三个位置之外，不存在全局依赖性，因此选择剩余数量最多的颜色是安全的，因为它可以最大限度地提高继续序列的机会。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（所有排列）| O(n!) | O(n) | 太慢了 |
 | 贪心于最后三个跟踪 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，创建一个将颜色映射到其计数的字典：`{'R': r, 'G': g, 'B': b}`。 这允许轻松访问和更新。 
2.初始化一个空列表`s`存储鬼火的序列。 
3. 当至少有一种颜色剩余数量时：

 1. 检查按剩余数量降序排列的所有颜色。 
2. 对于此顺序中的每种颜色，检查添加它是否会违反最后放置的约束：`s[-1]`和`s[-3]`。 如果`s`元素少于三个，则仅进行相关比较。 
3. 如果某种颜色通过了这些检查，则将其附加到`s`，减少其计数，并跳出颜色选择循环。 
4. 如果在不违反约束的情况下无法添加颜色，则终止此测试用例的序列。 
4. 转换`s`到一个字符串并存储或打印它。 

工作原理：通过始终选择具有最大可用计数且不违反直接邻接或距离 3 约束的颜色，该算法可确保序列在不违反规则的情况下无法进一步扩展。 不变的是每一步，`s`是有效的，并且颜色选择最大限度地提高了未来的灵活性。 任何选择的组合都不能产生更长的序列，因为当有较大计数的颜色可用时选择较小计数的颜色可能会导致颜色较早耗尽，从而减少潜在的最大长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        r, g, b = map(int, input().split())
        counts = {'R': r, 'G': g, 'B': b}
        s = []
        while any(counts[c] > 0 for c in counts):
            placed = False
            for color in sorted(counts, key=lambda x: -counts[x]):
                if counts[color] == 0:
                    continue
                if len(s) >= 1 and s[-1] == color:
                    continue
                if len(s) >= 3 and s[-3] == color:
                    continue
                s.append(color)
                counts[color] -= 1
                placed = True
                break
            if not placed:
                break
        print(''.join(s))

if __name__ == "__main__":
    solve()
```此代码使用一个简单的字典进行计数并保留序列列表`s`。 按剩余数量对颜色进行排序可确保贪婪选择。 邻接和距离 3 检查可防止无效放置。 这`while`当没有剩余颜色或在不违反约束的情况下无法放置任何颜色时，循环终止。 

## 工作示例

 输入示例：```
2
1 1 1
2 7 3
```第一种情况 (1 1 1) 的步骤跟踪：

 | 步骤| s | 计数 {'R','G','B'} | 行动|
 | ---| ---| ---| ---|
 | 1 | []| 右：1 右：1 右：1 | 选择 R（最大数）|
 | 2 | [R] | 右：0 右：1 右：1 | 选择G（最后使用R）|
 | 3 | [R，G] | 右：0 右：0 右：1 | 选择 B（最后使用 G）|
 | 4 | [红、绿、蓝] | 右：0 右：0 乙：0 | 终止 |

 输出：`RGB`第二种情况（2 7 3）：

 | 步骤| s | 计数| 行动|
 | ---| ---| ---| ---|
 | 1 | []| 右：2 右：7 右：3 | 选择 G |
 | 2 | [G]| 右：2 右：6 右：3 | 选择 R |
 | 3 | [G，R] | 右：1 右：6 右：3 | 选择 G（最后 3 个安全）|
 | 4 | [G，R，G] | 右：1 右：5 右：3 | 选择 B |

 | ... | ... | ... | 继续，直到计数完毕 |
