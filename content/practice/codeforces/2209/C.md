 ## 解决方案
 ## 问题理解

 我们被要求在长度为 的隐藏数组中找到零的位置$2n$，其中每个整数来自$1$到$n$只发生一次并且所有剩余位置为零。 我们并不明确知道该数组，但我们可以查询任意两个索引来检查它们是否包含相等的值。 交互器是自适应的，这意味着只要响应保持一致，它就可以重新排列查询中的非零元素。 我们的目标是最多使用$n+1$查询。 

输入提供$n$，它定义了数组的大小$2n$，并且可能存在多个测试用例。 输出是每个出现零的测试用例的单个索引。 主要困难是简单查询可能会超出查询限制，并且自适应交互器阻止我们假设数组是静态的。 

鉴于$n$可以达到$10^4$最多有$10^3$测试用例，一个$O(n^2)$比较所有对的蛮力方法的性能可达$10^8$操作，对于 2 秒的限制来说太慢了。 我们需要一个线性或近线性的策略。 当所有零聚集在一起时，会出现微妙的边缘情况：查询两个非零位置可能会始终返回零，直到我们包含零，这可能会误导天真的扫描。 例如，如果$a=[0,0,1,2]$，重复比较索引 3 和 4 将返回 0，这并不表示零。 

## 方法

 最简单的暴力方法是将每个索引与其他每个索引进行比较，直到找到零。 这是可行的，因为保证存在零，并且任何涉及零的不等对都会返回 0。问题是这需要最多$O(n^2)$查询，超出了大的限制$n$。 

更有效的方法利用了这样一个事实：$n$非零数和$n$零。 我们可以以结构化的方式查询数组：对连续元素进行配对$(1,2),(3,4),\dots$并跟踪哪些索引匹配。 任何返回相等的对必须要么都是零，要么都是相同的非零数字。 至关重要的是，因为每个非零数字只出现一次，所以任何返回相等的数字对都必须为零。 

最多允许我们解决问题的观察$n+1$查询的特点是，如果我们按顺序对元素进行配对，我们要么立即在匹配对中找到零，要么在末尾留下未配对的零。 这保证了始终可以通过线性数量的查询来定位一零，而与交互器的适应性无关。 该方法是确定性的，不依赖于了解非零数字的确切位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.初始化一个索引指针`i = 1`。 以 2 为步长迭代数组，查询连续的对`(i, i+1)`。 这确保我们有效地覆盖所有相邻元素。 
2. 对于每个查询，如果交互器返回 1，则表明该对包含相同的数字。 由于每个非零数都出现一次，因此唯一的可能性是两个元素都为零。 立即将该对中的一个指数报告为零。 
3. 如果交互器返回 0，则意味着该对包含两个不同的非零数字或一个零与一个非零。 移至下一对。 
4. 如果所有pair都返回0，则剩余未配对的元素中正好有一个0。 报告最后一个未配对的索引。 

为什么它有效：通过对连续元素进行配对，我们可以保证直接在匹配对中或通过穷举找到零，因为数组恰好有$n$零。 不变量是每个查询从考虑中消除一对元素，并且任何匹配的元素对都必须为零。 自适应交互器无法在不与之前的查询响应相矛盾的情况下阻止零的检测。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        found = False
        for i in range(1, 2*n, 2):
            print(f"? {i} {i+1}")
            sys.stdout.flush()
            res = int(input())
            if res == 1:
                print(f"! {i}")
                sys.stdout.flush()
                found = True
                break
        if not found:
            print(f"! {2*n}")
            sys.stdout.flush()

solve()
```该解决方案读取测试用例的数量，然后单独处理每个数组。 对于每个数组，我们查询连续的对，直到找到匹配项，报告匹配对的第一个索引。 如果没有配对匹配，则最后一个元素保证为零。 我们在每次查询后刷新输出以保持正确的交互。 使用步骤 2 最多可确保$n$每个数组的查询，位于$n+1$限制。 微妙之处在于处理最后一个元素是唯一零的情况； 在配对中跳过它仍然可以保证正确性。

 ## 边缘情况

 对于所有零都分组在末尾的情况，例如，`a=[1,2,3,0,0,0]`，算法查询连续对`(1,2),(3,4),(5,6)`。 只有最后一对匹配，产生响应 1。算法报告该对的第一个索引，正确识别零。 自适应交互器无法重新排列零以防止检测，因为它必须维护先前的查询响应。 该解决方案对于任何排列都是稳健的，无论零是聚集的、分散的还是孤立的。
