 ## 解决方案
 ## 问题理解

 我们得到了一系列怪物，每个怪物都有一个力量值。 我们也是从初始战斗力开始。 在任何时候，如果我们当前的力量至少是怪物的强度，我们就可以击败它，或者我们可以花费有限数量的特殊物品来将怪物的强度每次使用增加1。 

击败怪物是有益的，因为它可以根据怪物当前的强度来增加我们的战斗力，并且怪物被移除。 不同的是，我们可以在决定是否与它们战斗之前通过逐渐增加它们的强度来“塑造”最多 k 个怪物，但每次增量都会消耗一个触发器。 

目标是在选择最佳的强化和击杀顺序后最大化最终的战斗力。 

重要的互动是，增强怪物会使其更难立即杀死，但一旦我们变得更强，它可以使其更有利可图。 同时，尽早击杀可以增强我们的力量，从而能够接触到更强大的怪物。 

就 n 而言，约束很小，每个测​​试用例最多 100 个，但强度和初始功效的值最多可达 10^9，并且 k 可以非常大。 这立即排除了对触发器分布的任何状态空间搜索。 即使是对怪物进行简单的 DP 并剩余 k 也是不可能的，因为 k 是巨大的。 

该结构表明，我们并不是在全局范围内选择任意的增量分配，而是就怪物当前是否可用或是否需要稍微调整做出局部决策。 

当怪物刚刚太强大时，就会出现天真的贪婪思维的微妙失败案例，例如：

 输入：```
c = 10, k = 1
a = [12, 11]
```一个幼稚的策略可能会将触发器花在 12 上，使其变为 13，这会更糟糕。 正确的做法是将其花在 11 上，使其成为 12，以便 11 比 12 更早被杀死，从而改善未来的生长顺序。 

当过早使用所有触发器时会出现另一种极端情况，这会阻止稍后实现有益的杀戮。 

关键的困难是决定如何在多个怪物之间使用 k 增量，同时保持最佳的击杀顺序。 

## 方法

 暴力方法会尝试在怪物之间分配最多 k 个增量的所有方法以及杀戮顺序的所有排列。 对于每种配置，我们按照当前可行性的顺序模拟杀戮。 这会立即爆炸，因为即使决定如何分配 k 增量也是与大致（k+n 选择 n）可能性的组合，即使对于 k = 10^9 也是不可行的。 

关键的观察是，人字拖的唯一有意义的作用是改变怪物是否可以提前或推迟被杀死。 由于每个增量都会使怪物精确地改变 1，因此以当前功率 c 杀死怪物的成本是确定性的：max(0, a_i - c)。 我们永远不需要将怪物增加到c以上，因为这样做只会延迟其被杀死。 

因此，每个怪物都有一个相关的“激活成本”：在我们以当前的功率水平杀死它之前需要多少触发器。 一旦怪物变得可杀死，立即杀死它总是最佳的，因为它会增加c并且只会使以后的杀死变得更容易。 

这将问题简化为重复选择调整后成本适合剩余 k 和当前 c 的怪物，并且始终更喜欢能够在功率增长方面取得进展的怪物。 由于 n 很小，我们可以重复扫描并选择最佳的可行怪物，并随时更新 c。 

贪婪的结构出现了：在每一步，我们要么杀死任何当前可到达的怪物，要么花触发器进行解锁新怪物所需的最便宜的调整。

 ## 算法演练

 我们用当前的战斗力和剩余的触发器来模拟成长的过程。 

1.以当前战力c且所有怪物存活开始。 我们还跟踪剩余的 k 个触发器。 关键思想是，在任何时刻，只有 a_i ≤ c 的怪物才能立即可用。 
2.趁着还有怪物，我们首先尝试寻找不需要花人字拖就能直接杀死的怪物。 如果存在这样的怪物，我们将其移除并增加 c 的值。 这始终是最佳的，因为它可以在不消耗资源的情况下实现立即增长。 
3. 如果当前没有怪物可杀死，我们会考虑哪个怪物最容易被杀死。 对于每个活着的怪物，计算所需的成本 max(0, a_i - c)。 我们选择此类成本最小的。 这是释放下一个增长机会的最有效方式。 
4. 如果最便宜的所需成本大于 k，我们就停止，因为不可能有进一步的进展。 到那时，剩余的怪物太强大而无法被激活，并且停止是最佳选择，因为保存 k 没有未来的好处。 
5. 否则，我们将该成本花在所选怪物上，减少 k 并增加其有效强度以匹配 c。 调整后，怪物就可以在下一步中被杀死。 
6. 我们再次循环，在免费杀戮和最少的解锁操作之间交替，确保我们始终以最有效率的方式使用资源。 

### 为什么它有效

该算法保持了这样的不变性：我们永远不会使用触发器，除非它能够实现至少一次立即杀死。 任何不会导致立即终止的触发器分配都可以推迟，而不会影响未来的可行性，因为通过终止增加 c 只会使未来的阈值更容易满足。 因此，每次支出都与解锁下一次力量增益保持一致，并且贪婪地选择所需的最小调整确保我们随着时间的推移最大化可达到的杀戮数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c, k = map(int, input().split())
        a = list(map(int, input().split()))
        alive = [True] * n

        while True:
            changed = False

            # try free kills
            for i in range(n):
                if alive[i] and a[i] <= c:
                    c += a[i]
                    alive[i] = False
                    changed = True

            if changed:
                continue

            # find cheapest activation
            best_i = -1
            best_cost = 10**30

            for i in range(n):
                if alive[i]:
                    cost = max(0, a[i] - c)
                    if cost < best_cost:
                        best_cost = cost
                        best_i = i

            if best_i == -1:
                break

            if best_cost > k:
                break

            k -= best_cost
            a[best_i] = c  # now killable immediately

        # final clean-up: kill everything possible
        for i in range(n):
            if alive[i] and a[i] <= c:
                c += a[i]
                alive[i] = False

        print(c)

if __name__ == "__main__":
    solve()
```该解决方案的结构围绕重复应用两个操作：免费消耗所有当前可用的怪物，以及有针对性地解锁最便宜的未来怪物。 布尔数组跟踪哪些怪物保持活跃，主循环确保我们只在没有立即增长可用时才使用触发器。 

一个微妙的实现细节是最终的清理循环。 在触发器耗尽或无法进一步激活后，我们仍然必须消耗所有剩余的可到达的怪物，因为早期的解锁可能使额外的怪物符合条件而无需进一步的成本。 

作业`a[best_i] = c`是一种将怪物标记为完全可杀死的紧凑方式，无需进一步调整，确保它将在下一个自由阶段被消耗。

 ## 边缘情况

 一个关键的边缘情况是所有怪物最初都比 c 强并且 k 为零。 该算法立即进入激活搜索，找到正成本，并正确停止，因为不可能取得进展。 例如：

 输入：```
n = 2, c = 1, k = 0, a = [5, 6]
```由于每次成本都超过 k，因此不允许调整，因此答案仍为 1。 

另一种情况是当 k 足够大以减少 c 以下的最小怪物时，解锁级联。 例如：

 输入：```
n = 2, c = 3, k = 2, a = [6, 4]
```该算法在 4 上花费 1，立即启用杀戮，然后使用由此产生的增长来解锁其余的。 该不变量成立是因为每次支出后都会立即发生至少一次杀戮，从而确保不会浪费任何触发器。 

第三种情况是单次击杀后多个怪物同时变得可击杀。 免费杀戮循环确保所有此类怪物在任何进一步支出之前都被消耗掉，从而保持最佳顺序。
