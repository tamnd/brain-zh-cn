 ## 解决方案
 ## 问题理解

 我们有一条总长度的丝带`n`。 每个切割件必须恰好具有三个允许长度之一：`a`,`b`， 或者`c`。 我们的目标不仅仅是成功分割丝带，而是最大限度地增加我们获得的丝带总数。 

例如，如果色带长度为`5`允许的长度是`5`,`3`， 和`2`，将其切成单段长度`5`有效，但将其切成碎片`3 + 2`生产两件，这样更好。 

约束条件`n ≤ 4000`足够小，适合动态规划。 一个算法大致`O(n)`或者`O(n^2)`操作很容易符合限制。 探索所有可能的剪切序列的真正的强力递归仍然会在这些边界处终止，但它会多次重复相同的子问题并且变得不必要地昂贵。 

棘手的部分是并不是每个中间长度都是可以达到的。 粗心的实现可能会意外地将不可能的状态视为有效，并从中构建答案。 

考虑这个例子：```
7 5 2 5
```正确答案是`2`，因为我们可以削减`5 + 2`。 

假设 DP 数组用零初始化。 然后说明`dp[1]`会错误地显示为可达值`0`，随后的转换可以从中构建虚假的解决方案。 必须明确标记不可能的状态，通常用`-1`或负无穷大。 

当所有长度都相等时，会出现另一种微妙的情况：```
9 3 3 3
```正确答案是`3`。 某些实现尝试删除重复的长度或使用使转换复杂化的不必要的分支逻辑。 如果我们统一对待所有三个长度，问题就会变得简单得多。 

另一种边缘情况是最佳答案需要许多小切割而不是较大的有效切割：```
8 5 3 2
```有效的分解包括`5 + 3`有两块和`2 + 2 + 2 + 2`有四块。 总是先拿走最大的一块的贪婪策略在这里失败了。 

## 方法

 直接的暴力方法会尝试所有可能的切割序列。 从一条长度的丝带`x`，我们递归地尝试切断`a`,`b`， 和`c`，然后求解剩余长度。 

递归自然是正确的，因为每个有效的切割序列都被探索过。 问题是重复。 如果我们计算长度的最佳答案`20`，我们稍后可以从另一条路径重新计算它。 在最坏的情况下，递归调用的数量呈指数级增长。 

为了`n = 4000`，指数复杂度太大了。 甚至像`3^30`一秒钟之内的操作已经是不可能的了。 

关键的观察结果是该问题具有重叠的子问题。 丝带长度的最佳答案`x`仅取决于长度的最佳答案`x-a`,`x-b`， 和`x-c`。 

这使得这是一个经典的动态规划问题。 

我们定义：```
dp[i] = maximum number of pieces that can form length i
```如果无法形成长度，我们将其标记为不可能。 

从可到达的长度`i`，我们尝试使用每个允许的切割尺寸来扩展它。 每一次过渡都会增加一件作品。 

因为每个状态仅取决于较小的长度，所以我们可以迭代地计算答案`0`最多`n`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(3^n) | O(3^n) | O(n) 递归堆栈 | 太慢了 |
 | 最优动态规划| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.创建一个大小为DP的数组`n + 1`。 

各位置`dp[i]`存储可以产生总长度的最大件数`i`。 
2. 将所有状态初始化为不可能。 

我们使用`-1`对于不可能的状态，因为`0`是一个仅对长度有效的答案`0`。 
3. 设置`dp[0] = 0`。 

一段长度的丝带`0`需要零件，所以这是我们的起始状态。 
4. 迭代所有长度`0`到`n`。 

对于每个可达到的长度，尝试再添加一段长度`a`,`b`， 和`c`。 
5. 对于每个切割长度`x`在`{a, b, c}`：

如果`i + x ≤ n`， 更新：```
dp[i + x] = max(dp[i + x], dp[i] + 1)
```我们添加一根是因为我们要使用一根额外的丝带。 
6.处理完所有状态后，打印`dp[n]`。 

该声明保证至少存在一个有效的切割，因此最终的答案总是可达的。 

### 为什么它有效

 DP 不变量为：```
dp[i] always stores the maximum number of pieces for total length i
```我们从唯一确定正确的状态开始，`dp[0] = 0`。 

每当我们通过一个允许的切割来扩展可达状态时，我们就会创建另一个有效的功能区分解。 由于每个过渡都恰好添加一个片段，因此取最大值可以保留每个长度的最佳可能分解。 

每个有效的切割序列都对应于 DP 中的某些转换链。 由于探索了所有此类转变，因此最佳答案`n`保证被发现。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b, c = map(int, input().split())

    dp = [-1] * (n + 1)
    dp[0] = 0

    cuts = [a, b, c]

    for i in range(n + 1):
        if dp[i] == -1:
            continue

        for x in cuts:
            if i + x <= n:
                dp[i + x] = max(dp[i + x], dp[i] + 1)

    print(dp[n])

solve()
```DP 数组初始化为`-1`因此，不可达状态与有效状态明显分开。 这可以避免意外地从不可能的长度构建过渡。 

基本情况`dp[0] = 0`代表进行任何切割之前的空丝带。 

外环处理每个可到达的色带长度。 内循环尝试所有三个允许的剪切。 如果添加切割保持在范围内，我们将使用迄今为止看到的最佳件数更新目标状态。 

一个微妙的实现细节是跳过状态，其中`dp[i] == -1`。 如果没有这种检查，不可能的状态将错误地生成转换。 

另一个细节是使用`max`。 不同的分解可以达到相同的总长度，我们必须保留产生最多碎片的分解。 

## 工作示例

 ### 示例 1

 输入：```
5 5 3 2
```| 当前的`i`|`dp[i]`| 过渡 | 更新状态 |
 | --- | --- | --- | --- |
 | 0 | 0 | +5 | dp[5] = 1 |
 | 0 | 0 | +3 | dp[3] = 1 |
 | 0 | 0 | +2 | dp[2] = 1 |
 | 2 | 1 | +3 | dp[5] = 2 |
 | 3 | 1 | +2 | dp[5] = 2 |

 最终值：```
dp[5] = 2
```该轨迹显示了为什么需要最大化。 长度`5`首先直接用一件达到，然后使用`3 + 2`。 

### 示例 2

 输入：```
8 5 3 2
```| 当前的`i`|`dp[i]`| 过渡 | 更新状态 |
 | --- | --- | --- | --- |
 | 0 | 0 | +5 | dp[5] = 1 |
 | 0 | 0 | +3 | dp[3] = 1 |
 | 0 | 0 | +2 | dp[2] = 1 |

 最终值：```

```This example demonstrates why greedy strategies fail. 首先使用最大的一块只能得到两块，而重复较小的切割会产生四块。

# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n, a, b, c = map(int, input().split())

    dp = [-1] * (n + 1)
    dp[0] = 0

    for i in range(n + 1):
        if dp[i] == -1:
            continue

        for x in (a, b, c):
            if i + x <= n:
                dp[i + x] = max(dp[i + x], dp[i] + 1)

    print(dp[n])

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    backup_stdout = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup_stdout

    return out.getvalue().strip()

# provided sample
assert run("5 5 3 2\n") == "2", "sample 1"

# minimum-size valid input
assert run("1 1 1 1\n") == "1", "minimum case"

# all lengths equal
assert run("9 3 3 3\n") == "3", "all equal lengths"

# greedy would fail here
assert run("8 5 3 2\n") == "4", "many small cuts are optimal"

# boundary-style combination
assert run("7 5 2 5\n") == "2", "mixed reachable states"

# larger input
assert run("4000 1 2 3\n") == "4000", "maximum n with unit cuts"

 ## 边缘情况

 考虑这个输入：```
7 5 2 5
```DP 的开头是：```
dp[0] = 0
```从长度`0`，我们可以达到长度`5`和`2`。```
dp[5] = 1
dp[2] = 1
```从长度`2`，添加另一个`5`达到`7`:```
dp[7] = 2
```不可能的状态，例如`1`,`3`， 和`4`保持`-1`，因此不会从它们生成无效的转换。 

现在考虑相同的切割尺寸：```
9 3 3 3
```该算法仍然正常工作，因为每个转换都是独立处理的。 更新变为：```
dp[3] = 1
dp[6] = 2
dp[9] = 3
```重复值不需要特殊处理。 

最后，考虑贪婪失败的情况：```
8 5 3 2
```贪心策略选择`5`首先仅产生：```
5 + 3 = 8
```有两块。 

DP 探索所有可达分解，包括重复`2`削减：```
2 + 2 + 2 + 2 = 8
```正确地给出了四块。
