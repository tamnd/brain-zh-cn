 ## 解决方案
 ## 问题理解

 你至少需要`n`公斤土豆。 这家商店在不同的两天营业。 

第一天，每公斤花费`a`，并且有促销：每次付款`m`公斤，您可以免费额外获得一公斤。 购买`m`付费公斤给你`m + 1`总共公斤。 

第二天，每公斤花费`b`并且没有促销。 

您可以在任何一天购买任何非负整数公斤。 目标是至少获得`n`公斤，同时花费尽可能少的硬币。 

这些约束立即表明每个测试用例必须在恒定时间内解决。 数值可以达到`10^9`，因此迭代可能的购买金额是不可能的。 高达`10^4`测试用例，甚至`O(n)`每个测试用例的解决方案都太慢了。 

主要的困难是决定促销何时真正有用。 一个常见的错误是认为应该尽可能多地利用首日促销。 买的时候是假的`m`第一天公斤比简单购买要贵`m + 1`第二天公斤数。 

考虑：```
a = 10, b = 1, m = 2, n = 3
```一个促销块可以以 20 元的价格购买 3 公斤。第二天购买全部 3 公斤只需 3 元。在这里使用促销活动是灾难性的。 

另一个容易犯的错误是对最后一个不完整块的处理不当。 

考虑：```
a = 5, b = 4, m = 2, n = 4
```一整块升级块可以花费 10 获得 3 公斤。还需要 1 公斤。 第二天购买该公斤的费用为 4，总共 14。第二天购买全部 4 公斤的费用为 16。其余的必须单独处理。 

当出现第三种边缘情况时`n < m + 1`。 

考虑：```
a = 5, b = 4, m = 100, n = 2
```你甚至无法形成单一的晋升区块。 答案很简单`2 * min(a, b)`。 

## 方法

 暴力解决方案将尝试第一天购买的所有可能的公斤数，计算赠送后获得的公斤数，然后在第二天购买剩余的公斤。 这是正确的，因为它检查了每一个可行的策略。 

问题是可能性的数量与`n`， 和`n`或许`10^9`。 即使是一个测试用例也不可能以这种方式处理。 

关键的观察是促销在固定大小的块中进行。 支付费用`m`第一天产量公斤`m + 1`公斤。 

因此，促销块的成本$$m \cdot a$$并产生$$m+1$$公斤。 

如果获得`m+1`公斤完全是第二天的费用$$(m+1)\cdot b,$$那么我们应该比较这两个值。 

如果$$m a \ge (m+1)b,$$促销块永远不会比第二天购买相同数量的产品更好。 在这种情况下，我们应该完全忽略促销并以更便宜的每日价格购买每公斤。 

如果$$m a < (m+1)b,$$每个完整的促销块都是有益的。 然后我们使用尽可能多的完整块并单独处理剩余的公斤。

 | ---| ---| ---| ---|

 ## 算法演练

 1. 计算一个促销区块的成本：$$\text{promo} = m \cdot a.$$促销块正好给出`m + 1`公斤。 

1. 计算第二天完全获得相同公斤数的成本：$$\text{normal} = (m+1)\cdot b.$$1.如果$$m a \ge (m+1)b,$$忽略促销。 每公斤都应该以更便宜的每日价格购买，这样$$n \cdot \min(a,b).$$1. 否则，促销是值得的。 让$$q = \left\lfloor \frac{n}{m+1} \right\rfloor$$是完整促销块的数量。 

1.这些区块贡献$$q \cdot m \cdot a$$硬币。 

1.让$$r = n \bmod (m+1).$$这些公斤还不足以形成另一个完整的晋升块。 

1. 对于剩余的`r`公斤，使用每日两个价格中较便宜的价格购买每公斤：$$r \cdot \min(a,b).$$1. 添加两个贡献并打印结果。 

### 为什么它有效

 每当$$m a < (m+1)b,$$完整的促销块比第二天获得相同数量的公斤要便宜。 用任何其他方法替换整个块都无法改善答案。 

每当$$m a \ge (m+1)b,$$晋升块从来都不是有利的。 任何包含此类块的解决方案都可以通过在第二天购买相同数量的公斤来替换，而无需支付更高的成本。 

取完所有盈利的完整区块后，剩余数量小于`m+1`。 形成另一个促销块必然会购买额外的不必要的公斤。 对于剩余的公斤，每个单位都可以按成本价单独购买`min(a,b)`，这是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        a, b = map(int, input().split())
        n, m = map(int, input().split())

        if m * a >= (m + 1) * b:
            print(n * min(a, b))
        else:
            blocks = n // (m + 1)
            rem = n % (m + 1)

            ans = blocks * m * a
            ans += rem * min(a, b)

            print(ans)

solve()
```第一个分支处理促销与普通购买不具有竞争力的情况。 在这种情况下，每公斤都应该以更便宜的单价购买。 

第二个分支使用尽可能多的有利可图的促销块。 整数除法计算有多少个完整的组`m + 1`公斤符合目标数量。 其余部分独立处理。 

乘法顺序仅影响可读性，因为 Python 整数具有任意精度。 在具有固定宽度整数的语言中，需要 64 位算术，因为值可能达到大约`10^18`。 

一个常见的除一错误是除以`m`而不是`m + 1`。 促销活动产生`m + 1`公斤，因此必须使用该尺寸来计算完整的块。

import sys

def run(inp: str) -> str:

    input = sys.stdin.readline
    t = int(input())

        a, b = map(int, input().split())

 ## 边缘情况

 考虑：```
a = 10
b = 1
n = 3
m = 2
```完整的升级块成本为 20，产量为 3 公斤。 第二天买 3 公斤只需 3 公斤。$$20 \ge 3,$$算法进入第一个分支并返回$$3 \cdot 1 = 3.$$这正确地避免了晋升。 

考虑：```
a = 5
b = 4
n = 2
m = 100
```无法完成升级区块，因为一区块将产生 101 公斤。 该算法计算零个完整块并以成本购买剩余的两公斤`min(5,4)=4`，给出 8。 

考虑：```
a = 3
b = 10
n = 9
m = 2
```每个升级块的成本为 6，产量为 3 公斤。 三个完整的块恰好提供了所需的数量。 余数为零，所以答案很简单$$3 \cdot 6 = 18.$$这验证了在不购买不必要的公斤的情况下处理了精确的整除性。
