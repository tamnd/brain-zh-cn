 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，我们关心它的前缀和为零的频率。 位置处的前缀和`i`是第一个的总和`i`元素，然后我们通过计算这些前缀和中有多少个恰好为零来对数组进行评分。 

不同的是，一些元素最初为零，并且每个这样的位置都是灵活的：我们可以用我们想要的任何整数替换它，可能对不同的零位置使用不同的值。 目标是选择替换，以使零前缀和的数量变得尽可能大。 

从约束的角度来看，所有测试用例的总输入大小可达`2 · 10^5`。 这立即排除了任何重复重新计算许多候选修改的前缀和的二次策略。 任何可接受的东西本质上都必须在每个测试用例中处理每个元素恒定的次数。 

当所有值都不为零时，会出现微妙的边缘情况。 在这种情况下，根本不允许进行任何操作，因此答案由原始前缀结构固定。 假设我们总是可以使用运算“修复”前缀和的天真的方法会错误地高估分数。 另一个边缘情况是零频繁出现时。 粗心的贪婪方法可能会假设每个零都可以独立地将前缀和强制为零，但是只有当我们了解前缀和如何在全球范围内演变时，选择任意值的能力才会有所帮助。 

## 方法

 思考该问题的一种直接方法是模拟替换零条目的所有可能选择。 对于每个零位置，我们可以尝试可能有助于创建未来零前缀和的所有整数，然后重新计算前缀和。 这在原则上是正确的，但完全不可行：即使将值限制为一个小集合，配置的数量也会随着零的数量呈指数增长，并且每个配置都需要完整扫描来计算前缀和，在最坏的情况下给出指数时间。 

关键的观察结果是，分数仅取决于前缀和，并且前缀和线性演变。 当我们遇到零时，我们可以完全控制此时调整运行总和的程度。 这意味着每个零就像一个“重置机会”：我们可以选择它的值，以便该位置的前缀和恰好为零，而不管之前的历史记录如何。 然而，错误地使用这种自由可能会破坏未来的机会，因为改变一个位置会影响所有后面的前缀和。 

正确的视角是从左到右处理数组，同时跟踪当前的前缀和。 每当我们到达原始值为零的位置时，我们就可以决定是否使用它在该确切位置“强制”零前缀和。 如果我们这样做，我们实际上将运行总和重置为零。 每当当前前缀和尚未为零时，这都是有益的，因为它允许我们创建额外的计数零，而不会失去随后持续继续的能力。 

这将问题简化为贪婪地计算我们可以强制执行零前缀和的次数，并限制在每次强制重置后，我们从零重新开始累加。

 ## 算法演练

 我们独立处理每个测试用例并扫描一次数组。 

1. 初始化运行前缀和`s = 0`和一个柜台`ans = 0`。 
2. 从左到右迭代数组。 对于每个位置`i`， 添加`a[i]`到`s`。 如果我们在此位置不做任何特殊操作，这将模拟前缀和。 
3. 如果当前前缀和`s`变为零，增量`ans`因为我们已经实现了有效的零前缀。 
4.如果`a[i] == 0`，我们考虑用这个位置作为替换点。 如果当前前缀和不为零，我们设置`ans += 1`并重置`s = 0`。 原因是我们可以为这个零分配一个值，精确地取消当前的前缀和，在位置创建一个新的零前缀`i`，然后重新开始累加。 
5. 继续直到数组末尾。 

核心决定是每个零值位置都可以被忽略或用于强制前缀重置。 仅当它增加零前缀的数量时才有用，这种情况发生在运行总和尚未为零时。 

### 为什么它有效

 运行前缀总和完全决定了前缀是否对分数有贡献。 零位置处的任何修改都会通过运行总计统一影响所有未来的前缀和。 因此，每个零都充当一个潜在的“切入点”，我们可以将系统重置为干净状态。 

不变量是处理后索引`i`，该算法使用第一个中的最佳选择来维护可实现的最大可能数量的零前缀和`i`元素，同时保持当前模拟的前缀和与所选决策一致。 当前缀和非零时，任何不重置为零的替代策略都无法在不降低以后灵活性的情况下增加该位置的分数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        s = 0
        ans = 0
        
        for x in a:
            s += x
            
            if s == 0:
                ans += 1
            
            if x == 0:
                if s != 0:
                    ans += 1
                    s = 0
        
        print(ans)

if __name__ == "__main__":
    solve()
```实现直接遵循从左到右的模拟。 前缀和`s`表示应用所选修改后的当前累积值。 支票`s == 0`无需任何修改即可解释自然的零前缀出现。 第二个条件处理零位置，我们主动选择一个值来强制重置。 

重置`s`归零是至关重要的，因为一旦我们使用零位置来取消当前总和，未来的前缀总和就应该相对于新基线进行计算。 如果没有此重置，以后的计算将错误地累积过去的贡献。

 ## 边缘情况

 带有单个零的最小输入直接演示了重置行为。 和`a = [0]`，前缀和最初为零，算法计算一次，然后也将零位置识别为重置机会，但由于总和已经为零，因此避免了错误的重复计算，仍然返回`1`。 

为了`a = [1, 2, 3]`，没有要操作的零，并且没有前缀和为零，所以答案保持不变`0`。 该算法从不触发重置分支，而只是在整个过程中累积非零前缀。 

对于全零序列，每个位置都可用于强制重置。 每一步都会产生一个新的零前缀，因此结果是`n`，贪婪重置规则通过在处理下一个元素之前在总和非零的每个位置进行重置来正确实现此目的。
