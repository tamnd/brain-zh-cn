 ## 解决方案
 ## 问题理解

 我们得到了一个二进制网格。 一个单元格包含`1`是一个黑曜石块和一个包含`0`是空的。 

我们可以翻转任何单元格，改变`0`到`1`或者`1`到`0`，每次翻转花费一次。 

我们的目标是找到一个子矩形，可以用最少的翻转次数将其转变为有效的门户。 

门户具有非常具体的结构。 该矩形必须至少有 5 行和至少 4 列。 边界上的每个非角单元都必须是`1`，而每个内部单元必须是`0`。 四个角单元完全不相关，可以包含任一值。 

测试用例的答案是至少需要翻转多少次才能使至少一个子矩形成为门户。 

约束是直接搜索不可能的第一个线索。 两个维度都可以达到400。通过选择两行和两列来确定一个矩形，这已经大致给出了$400^4$的可能性。 即使有效地检查单个矩形也无法保存这样的解决方案。 

该语句还包含一个不寻常的保证：测试用例中所有行计数的总和最多为 400，所有列计数的总和也最多为 400。这意味着解决方案$O(n^2m)$或者$O(nm^2)$是可以接受的，同时$O(n^2m^2)$太大了。 

一个微妙的细节是角落并不重要。 

考虑：```
1111
1001
1001
1001
1111
```这看起来已经像一个门户了。 现在更改所有四个角：```
0110
1001
1001
1001
0110
```它仍然是一个有效的入口，因为只有非角边界单元受到约束。 

另一个容易犯的错误是忘记高度必须至少为 5。 

例如：```
1111
1001
1001
1111
```该矩形具有正确的边框图案，但高度为 4，因此它不是门户。 

第三个常见错误是在合并行和列的成本时对边界单元进行两次计数。 最佳解决方案仔细地将内部需求与边界需求分开，因此每个单元只贡献一次。 

## 方法

 蛮力的想法很简单。 枚举高度至少为 5、宽度至少为 4 的每个可能的矩形。对于每个矩形，计算必须更改的单元格数量。 

细胞贡献：

 - 0 如果它已经匹配所需的状态。 
- 1 如果必须翻转。 

所有矩形中的最小值就是答案。 

问题是矩形的数量。 有$O(n^2m^2)$可能的选择。 和$n=m=400$，这大约是$2.5\times10^{10}$矩形。 即使在恒定时间内检查每个矩形也是没有希望的。 

关键的观察结果是门户形状是高度结构化的。 

假设我们修复门户的顶行和底行。 高度必须至少为 5，因此它们之间的距离至少为 4。 

对于固定的一对行，我们只需要选择左右列即可。 

现在逐列思考。 

对于候选左边框列，两行之间的每个中间单元格必须变为`1`。 

对于候选右边框列，也是如此。 

对于严格位于矩形内部的每一列，边界之间的所有单元格都必须变为`0`，而该列的顶部和底部边框单元格必须变为`1`。 

每列的成本贡献可以独立计算。 之后，问题就变成了列上的滑动窗口优化。 

这将搜索从同时选择四个边界减少到选择行对，然后以数据结构样式最小维护扫描列。 

接受的解决方案运行于$O(n^2m)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²m²) 个矩形，即使使用 O(1) 个检查 | O(纳米) | 太慢了 |
 | 最佳 | O(n²m) | O(m) 加上前缀和 | 已接受 |

 ## 算法演练

 ### 预计算

 对于每一列，我们需要快速知道两行之间出现了多少个。 

构建列前缀和：$$col[j][i]$$存储列中的个数`j`从行`1`穿过行`i`。 

那么任意垂直段查询就变成了O(1)。 

### 修复顶行和底行

 1. 枚举每对行`(top, bottom)`这样`bottom - top >= 4`。 
2.让`h = bottom - top - 1`，内部行数。 
3. 对于每一列`c`，计算三个值。 

该列内部的个数：$$insideOnes$$该列用作侧边框的成本。 

侧边框上的内部单元格必须全部是`1`， 所以：$$sideCost = h - insideOnes$$4. 计算该柱用作内柱的成本。 

顶部和底部单元格必须是`1`。 

所有中间单元格必须是`0`。 

让$$interiorCost = (grid[top][c]==0) +(grid[bottom][c]==0) + insideOnes$$因为每个室内`1`必须翻转到`0`。 

### 转化问题

 1.假设栏`r`被选为右边界。 

然后左边框和右边框之间的列成为内部列。 
2. 定义$$value[c] = sideCost[c] - interiorCost[c]$$这衡量了如果列我们支付多少额外费用`c`成为侧边框而不是内部柱。 
3. 从左到右扫描列时，尽可能保持最佳左边框至少早三列。 

宽度必须至少为 4，因此：$$right - left \ge 3$$4. 对于每个右边框列，计算$$total = sideCost[right] + prefixInteriorCost(right-1) + bestLeft$$在哪里`bestLeft`存储最小值$$sideCost[left] - prefixInteriorCost(left)$$在所有有效的左边界上。 
5.更新全局答案。 

### 为什么它有效

 对于固定的顶行和底行，每一列都属于以下三个类别之一：

 - 左边框，
 - 右边框，
 - 内部柱。 

矩形的成本是这些类别的贡献之和。 

内部列提供范围总和，可以使用前缀总和来表示。 相对于内部，左边框提供了额外的调整。 这会将矩形优化转换为查找涉及左侧一列和右侧一列的表达式的最小值。 

扫描保留了迄今为止看到的最佳左边框，因此当前行对的每个有效矩形都被仅考虑一次。 由于枚举了所有行对，因此找到了所有入口的最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())
        g = [list(map(int, input().strip())) for _ in range(n)]

        col = [[0] * (n + 1) for _ in range(m)]
        for j in range(m):
            for i in range(n):
                col[j][i + 1] = col[j][i] + g[i][j]

        ans = 10**9

        for top in range(n):
            for bottom in range(top + 4, n):
                h = bottom - top - 1

                side = [0] * m
                interior = [0] * m

                for c in range(m):
                    inside_ones = (
                        col[c][bottom] -
                        col[c][top + 1]
                    )

                    side[c] = h - inside_ones

                    interior[c] = (
                        inside_ones +
                        (1 - g[top][c]) +
                        (1 - g[bottom][c])
                    )

                pref = [0] * (m + 1)
                for c in range(m):
                    pref[c + 1] = pref[c] + interior[c]

                best = side[0] - pref[1]

                for right in range(3, m):
                    left_candidate = right - 3
                    best = min(
                        best,
                        side[left_candidate] -
                        pref[left_candidate + 1]
                    )

                    cur = (
                        side[right]
                        + pref[right]
                        + best
                    )

                    ans = min(ans, cur)

        print(ans)

solve()
```列前缀和是实现的基础。 它们使我们能够在恒定的时间内计算任何垂直段中的 1 的数量。 

对于每个固定的行对，数组`side`和`interior`将每个列的成本贡献存储在两个可能的重要角色下。 这些值是独立计算的，这使得以后的优化成为可能。 

数组`pref`存储前缀和`interior`。 这让我们可以通过简单的前缀差异来获取两个边界之间所有内部列的成本。 

变量`best`是重点优化。 当扫描到达可以作为右边界的列时，`best`已经包含最便宜的有效左边框。 由于宽度必须至少为四，因此仅允许早于至少三个位置的列输入此最小值。 

最常见的实现错误是前缀索引中的相差一错误。 表达式`pref[left + 1]`是故意的，因为专栏`left`其本身不得计入内部列。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        g = [list(map(int, input().strip())) for _ in range(n)]

        col = [[0] * (n + 1) for _ in range(m)]
        for j in range(m):
            for i in range(n):
                col[j][i + 1] = col[j][i] + g[i][j]

        ans = 10**9

        for top in range(n):
            for bottom in range(top + 4, n):
                h = bottom - top - 1

                side = [0] * m
                interior = [0] * m

                for c in range(m):
                    inside = col[c][bottom] - col[c][top + 1]
                    side[c] = h - inside
                    interior[c] = (
                        inside +
                        (1 - g[top][c]) +
                        (1 - g[bottom][c])
                    )

                pref = [0] * (m + 1)
                for c in range(m):
                    pref[c + 1] = pref[c] + interior[c]

                best = side[0] - pref[1]

                for r in range(3, m):
                    best = min(
                        best,
                        side[r - 3] - pref[r - 2]
                    )
                    ans = min(
                        ans,
                        side[r] + pref[r] + best
                    )

        out.append(str(ans))

    return "\n".join(out) + "\n"

 ## 边缘情况

 ### 角点无关紧要

 输入：```
1
5 4
0110
1001
1001
1001
0110
```所有四个角都是`0`。 

该算法从不包含任何一个角点`sideCost`或者`interiorCost`。 边界要求仅适用于非角边界单元，与定义完全匹配。 答案就变成了`0`。 

### 最小尺寸

 输入：```
1
5 4
0000
0000
0000
0000
0000
```恰好有一个可能的矩形。 扫描仍然有效，因为第一个有效的右边框是第 3 列，对应于宽度 4。不需要特殊处理。 

### 宽度正好是四

 输入：```
1
5 4
1111
1001
1001
1001
1111
```该矩形只有两个内部柱。 

条件`right - left >= 3`正好允许这个宽度。 一个常见的错误是需要更大的间隙并意外地拒绝唯一有效的矩形。 

### 高度正好五

 输入：```
1
5 5
11111
10001
10001
10001
11111
```这对`(top=0,bottom=4)`被处理是因为算法从`bottom = top + 4`。 任何更严格的条件都会错误地跳过最小高度的有效门户。
