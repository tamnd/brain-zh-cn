 ## 解决方案
 ## 问题理解

 我们有一个代表蛋糕的小矩形网格。 每个单元格要么是一个普通的蛋糕单元格（`.`）或含有草莓（`S`）。 

蛋糕终结者可能会重复选择整行或整列并吃掉其中的所有细胞，但前提是该行或列根本不包含草莓。 已经被吃掉的细胞并不重要。 只要行或列包含至少一个未吃掉的单元格，以后仍可以选择该行或列。 

目标是找到可以被吃掉的最大细胞数量。 

网格尺寸最多为 10 × 10。这意味着总共最多有 100 个单元格。 由于限制如此之小，即使效率相对较低的方法也足够快。 挑战不在于性能，而在于正确计算可以被吃掉的细胞，而无需重复计算所选行和列之间的交叉点。 

关键的观察结果是，吃操作的顺序并不重要。 如果一行中没有草莓，则该行中的每个细胞最终都可以被吃掉。 如果一列中没有草莓，则该列中的每个细胞最终都会被吃掉。 如果一个细胞属于至少一排无草莓或一列无草莓的细胞，则该细胞是可食用的。 

一些边缘情况可能会导致错误。 

考虑一个网格，其中一个单元格既属于安全行又属于安全列：```
2 2
..
..
```正确答案是：```
4
```粗心的解决方案可能会先对安全行中的所有单元格进行计数，然后对安全列中的所有单元格进行计数，从而获得 8 而不是 4，因为每个单元格都会被计数两次。 

另一个重要的情况是没有行和列是安全的：```
2 2
S.
.S
```正确答案是：```
0
```每行都有一个草莓，每列都有一个草莓，所以不可能移动。 

第三种情况是只有行是安全的：```
2 3
...
S.S
```正确答案是：```
3
```第一排可以吃完。 没有一个柱子是安全的，因为每个柱子的某个地方都含有一个草莓。 答案正是安全行的大小。 

## 方法

 蛮力的观点是考虑哪些行和列可以被吃掉。 每一个没有草莓的行总是值得采取，每一个没有草莓的列总是值得采取。 识别出它们后，我们可以模拟所有被吃掉的细胞并计算有多少不同的细胞被吃掉。 

由于网格最多包含 100 个单元格，因此即使重复检查每个单元格也是完全可以接受的。 主要挑战是避免重复计算位于安全行和安全列交叉处的单元格。 

关键的观察是，当且仅当以下至少一项为真时，细胞才是可食用的：

 1. 该行没有草莓。 
2. 其柱中不含草莓。 

如果任一条件成立，则可以在某个时刻选择相应的行或列，从而导致该单元格被吃掉。 如果这两个条件都不成立，则其行和列都包含草莓，因此没有合法的操作可以到达该单元格。 

这将问题转化为简单的标记任务。 首先确定哪些行是安全的，哪些列是安全的。 然后检查每个细胞。 计算它的行​​是否安全或列是否安全。 

### 复杂性比较

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 使用访问过的单元进行强力模拟 | O(r·c) | O(r·c) | 已接受 |
 | 最佳行/列打标 | O(r·c) | O(r + c) | 已接受 |

 由于网格很小，两种方法都很容易满足限制。 第二种方法更简单，直接表达关键观察结果。 

## 算法演练

 1. 读取网格。 
2. 对于每一行，检查是否包含草莓。 

如果某行不包含`S`，将其标记为安全。 
3. 对于每一列，检查它是否包含草莓。 

如果某列不包含`S`，将其标记为安全。 
4. 迭代网格的每个单元格。 
5. 如果单元格的行是安全的或单元格的列是安全的，则在答案中加 1。 

这样的细胞最终可以通过至少一次合法的手术被吃掉。 
6. 输出最终计数。 

### 为什么它有效

 总是可以选择没有草莓的行，因此该行中的每个单元格都是可食用的。 同样，始终可以选择没有草莓的列，因此该列中的每个单元格都是可食用的。 

如果一个单元格既不属于安全行也不属于安全列，那么它的行和列都包含草莓。 由于只能选择完全不含草莓的行和列，因此任何合法操作都不能吃掉该单元格。 

因此，可食用细胞正是那些行安全或列安全的细胞。 精确计数这些细胞可以得出被吃掉的细胞的最大可能数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

r, c = map(int, input().split())
grid = [input().strip() for _ in range(r)]

safe_row = [False] * r
safe_col = [False] * c

for i in range(r):
    if 'S' not in grid[i]:
        safe_row[i] = True

for j in range(c):
    ok = True
    for i in range(r):
        if grid[i][j] == 'S':
            ok = False
            break
    safe_col[j] = ok

answer = 0

for i in range(r):
    for j in range(c):
        if safe_row[i] or safe_col[j]:
            answer += 1

print(answer)
```第一部分标识所有没有草莓的行。 使用 Python 的字符串成员资格检查使这变得非常简洁。 

第二部分独立扫描每一列。 仅当没有行包含某个列时，该列才被标记为安全`S`在那一栏里。 

最后的嵌套循环对单元格进行计数。 该条件使用逻辑“或”，因为当单元格的行或列可以被食用时，该单元格就是可食用的。 

一个常见的错误是先对安全行中的所有单元格进行计数，然后再分别对安全列中的所有单元格进行计数。 交叉点将被计算两次。 对每个单元格检查一次就可以完全避免这个问题。

# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    r, c = map(int, input().split())
    grid = [input().strip() for _ in range(r)]

    safe_row = [False] * r
    safe_col = [False] * c

    for i in range(r):
        if 'S' not in grid[i]:
            safe_row[i] = True

    for j in range(c):
        safe_col[j] = True
        for i in range(r):
            if grid[i][j] == 'S':
                safe_col[j] = False
                break

    ans = 0
    for i in range(r):
        for j in range(c):
            if safe_row[i] or safe_col[j]:
                ans += 1

    return str(ans)

 ## 边缘情况

 考虑完全空的蛋糕：```
2 2
..
..
```每一行都是安全的，每一列都是安全的。 该算法将所有行和列标记为安全，然后对所有四个单元格进行一次计数。 输出是：```
4
```这避免了常见的重复计算错误，即产生 8。 

考虑一个蛋糕，其中每行每列都包含一个草莓：```
2 2
S.
.S
```没有行被标记为安全，也没有列被标记为安全。 在最后一次计数过程中，每个单元格均不符合条件`safe_row[i] or safe_col[j]`。 答案是：```
0
```考虑仅按行进餐的情况：```
2 3
...
S.S
```第一排是安全的。 没有一列是安全的，因为每一列在网格中的某处至少包含一个草莓。 该算法精确计算第一行的三个单元格并返回：```
3
```这证实了行和列是独立处理的，并且细胞只需要这两个条件之一就可以食用。
