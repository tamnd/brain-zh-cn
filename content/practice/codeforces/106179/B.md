 ## 解决方案
 ## 问题理解

 该问题询问是否可以重新排列一个数组，使得从两端对称放置的每对元素都足够接近。 选择数组的某种排列后，第一个值和最后一个值最多必须相差`d`，第二个和倒数第二个值最多必须相差`d`， 等等。 任务只是确定这样的顺序是否存在。 最初的问题来自 Codeforces Gym 106179。 

输入包含多个测试用例。 每个测试用例给出了数组的长度，允许的最大差值`d`，以及数组中的值。 输出是`YES`如果某些重排满足所有对称对条件，否则是`NO`。 

所有测试用例中数组元素的总数最多为 2000，单个数组的长度可以为 2000。这意味着`O(n^2)`解决方案在技术上是可行的，但搜索更简单的结构很有用，因为正在检查的操作是基于排序的。 值本身可以大到`10^9`，因此解决方案应避免关于小范围或频率阵列的假设。 

一个常见的错误是只检查最小值和最大值是否在距离内`d`。 这个条件是必要的，但不是充分的。 例如：```
1
4 5
1 4 10 12
```最小值和最大值的区别在于`11`，所以这已经失败了，但是当极端情况良好但内部对失败时，可能会出现不同的错误。 考虑：```
1
6 5
1 5 6 10 11 12
```最小值和最大值的不同之处在于`11`，所以这显然也是不可能的。 更有用的边缘情况是单个元素：```
1
1 0
100
```答案是`YES`。 没有一对违反条件，并且任何盲目检查镜像索引而不处理中心位置的实现都可能错误地拒绝它。 

另一个边缘情况是当`d`为零。 例如：```
1
4 0
7 7 7 8
```答案是`NO`。 每个镜像对必须包含完全相同的值，并且单个`8`无法匹配。 仅在排序后检查相邻差异的解决方案可能会错过这一点，因为数组几乎是均匀的。 

## 方法

 一种直接的方法是尝试可能的重新排列并检查每个对称对是否有效。 这是正确的，因为它准确地检查了问题所需的条件。 然而，可能的订单数量是`n!`，即使对于小型阵列，这也是不可能的。 

更合理的强力方法是对数组进行排序并尝试贪婪地构建对，或者对对进行回溯。 问题是可能的配对分配数量仍然增长得太快。 和`n = 2000`，甚至一个`O(n^2)`方法已经进行了大约四百万次操作，而任何涉及探索许多配对的操作都远远超出了限制。 

关键的观察结果是，只有一对内的最大距离才重要。 如果两个值相距较远，则不应将它们放在一起。 排序会立即显示最严格的对：最大的元素必须与数组下端的某个元素配对。 最小的元素也有同样的问题。 

最佳排列将最小剩余值与最大剩余值重复配对。 这不仅仅是一种方便的构造。 它给出了将阵列分割成镜像对的所有方法中尽可能小的最大对差。 如果这种安排失败，则没有其他重新安排可以使极值适合，因为向内移动任一极值都会迫使另一个值取代其位置并产生相等或更大的间隙。 

将数组排序后为`b`，唯一需要检查的是是否：`b[n - 1 - i] - b[i] <= d`对于每个镜像索引`i`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 排序和检查镜像对 | O(n log n) | O(n log n) | O(1) 额外 | 已接受 |

 ## 算法演练

 1. 对数组进行非降序排序。 排序暴露了最极端的可能对，这些对决定了排列是否可以存在。 
2. 比较最小元素和最大元素。 如果它们的差异大于`d`，答案立即`NO`，因为这两个极端不能同时放入有效的镜像位置。 
3. 继续向内比较第二小的和第二大的，然后比较第三小的和第三大的，直到到达中间。 每次比较都代表最佳排列中的一个可能的镜像对。 
4. 如果所有镜像对满足距离限制，则输出`YES`。 排序的镜像排列本身就是一个有效的构造。 

为什么它有效：

 排序后，考虑最大的元素。 它需要一个远方的伙伴`d`。 将其与除最大剩余可能值之一之外的任何值配对只能使配对更小并且差异更大。 同样的论点也适用于最小元素。 删除这两个值会在较小的数组上留下相同的问题，因此重复配对极端可以提供最佳的排列。 如果即使这个排列包含无效对，则所有其他排列也必须包含无效对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, d = map(int, input().split())
        a = list(map(int, input().split()))

        a.sort()

        ok = True
        for i in range(n // 2):
            if a[n - 1 - i] - a[i] > d:
                ok = False
                break

        ans.append("YES" if ok else "NO")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```使用读取输入`sys.stdin.readline`因为可能有很多测试用例。 该解决方案首先对每个数组进行排序，这是唯一改变顺序的操作。 

该循环仅检查排序数组的前半部分。 各指标`i`与`n - 1 - i`，这是它在排序版本中的镜像位置。 奇数大小的数组的中间元素将被忽略，因为它没有伙伴。 

该比较使用 Python 整数之间的减法，因此大值可达`10^9`均得到安全处理。 尽管渐近复杂度保持不变，但找到无效对后提前退出可以避免不必要的检查。

 ## 边缘情况

 对于单元素情况：```
1
1 0
42
```排序后的数组是`[42]`。 该循环执行零次迭代，因为`n // 2`为零。 算法输出`YES`，匹配没有任何一对可以违反条件的事实。 

对于零距离情况：```
1
4 0
7 7 7 8
```排序后，数组为`[7, 7, 7, 8]`。 第一次镜像比较检查`8 - 7 = 1`，大于零，因此算法停止并打印`NO`。 无与伦比的`8`不能通过重新排列来隐藏，因为它必须属于某个镜像对。 

对于仅检查全局最小值和最大值还不够的情况，算法会检查每个镜像层。 例如：```
1
5 3
1 3 5 7 9
```排序后的数组保持不变。 外对给出`9 - 1 = 8`，已经太大了，所以答案是`NO`。 即使极端情况有效，内部比较仍然会被检查，以防止部分条件的错误接受。
