 ## 解决方案
 ## 问题理解

 我们给出了一系列高度`a`长度`n`，其中每个高度都介于`0`和`k`。 如果可以通过重复选择包含至少两个位置的区间并将该区间中的每个值减一来完全删除该序列，则该序列被认为是良好的。 

任务是计算有多少种可能的高度序列是好的。 答案需要对给定素数取模`p`。 

区间操作看起来像是一个模拟问题，但实际操作并不是我们应该统计的。 有用的问题是序列是否在每个位置周围都有足够的支持以允许其所有值消失。 

如果我们将序列扩展为`a[0] = 0`和`a[n+1] = 0`, 一个位置`i`如果它的值大于其两个邻居的总支持度，则无法删除：$$a_i > a_{i-1} + a_{i+1}$$这样的峰值无法充分降低，因为每个操作都涉及`i`还必须涉及其邻居之一。 Conversely, if no such peak exists, the sequence can be removed by combining interval reductions.

 The constraints are the reason the main challenge is counting rather than checking. 值限制为`k <= n`和`n <= 3000`，总和为`n^2`在所有有界测试用例上。 三次动态规划解决方案已经太慢了，因为`3000^3`操作远远超出了几秒钟的时间。 我们需要一个接近的方法`O(n^2)`。 

一些边缘情况很容易被忽略。 

必须拒绝具有大孤立值的序列。 例如：```
Input:
n = 3, k = 5
a = [0, 5, 0]
```中间的值大于其邻居的总和，因此正确的贡献为零。 仅检查总和或尝试贪婪地删除间隔的解决方案可能会错误地接受它。 

边界的行为就像额外的零。 例如：```
Input:
n = 3, k = 1
a = [1, 0, 0]
```第一个位置违反了条件，因为`1 > 0 + 0`，所以这样不好。 忘记数组外部的人工零会导致这种情况计数不正确。 

一个序列可以包含许多相等的值并且仍然有效：```
Input:
n = 3, k = 1
a = [1, 1, 1]
```中间位置有足够的支撑，两端有相邻值和外部零支撑。 答案包括这个序列。 

## 方法

 直接的方法是生成每一个可能的序列并测试它是否良好。 有`(k+1)^n`序列，因此即使使用恒定时间检查器，这也很快变得不可能。 例如，当`n = k = 3000`，搜索空间非常大。 

更合理的第一个动态编程思想是从左到右构建序列，同时记住前两个值。 选择时`a[i]`，唯一创建的新条件涉及`a[i-1]`,`a[i]`， 和`a[i+1]`，因此保留两个先前的值可以提供足够的信息。 这个州大约有`n * k^2`可能性，并且每个转换都可以使用前缀和进行优化。 对于更简单的版本来说已经足够了，但对于硬约束来说仍然太大，因为它在值维度上执行了太多的工作。 

关键的观察是无效位置不能相邻。 假设两个相邻位置都无效：$$a_i > a_{i-1}+a_{i+1}$$和$$a_{i+1} > a_i+a_{i+2}$$添加它们给出：$$a_i+a_{i+1} > a_{i-1}+a_i+a_{i+1}+a_{i+2}$$这需要非负值`a_{i-1}+a_{i+2}`是消极的。 这是不可能的。 

这个属性允许我们使用包含-排除。 我们不是记住以前的值，而是计算所有序列并减去当前位置是第一个无效位置的序列。 由于无效位置不能相互接触，因此不需要跟踪先前的位置。 

让`dp[i][x]`表示以 value 结尾的前缀的包含-排除加权计数`x`加工后位置`i`。 转换修复当前值并删除当前位置违反条件的情况。 可以使用后面两个位置的值来计算无效案例，这给出了`O(nk)`带有前缀和的转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O((k+1)^n) | O((k+1)^n) | O(n) | 太慢了 |
 | DP | 前两个值 O(nk²) | O(k²) | 硬版本太慢|
 | 包含-排除 DP | O(nk) | O(nk) | O(k) | 已接受 |

 ## 算法演练

 1. 初始化空前缀的动态编程状态。 数组之前的外部值固定为零，因此唯一的起始状态是 value`0`。 
2. 从左到右处理位置。 对于每一个可能的值`j`在当前位置，首先考虑以前一个位置结尾的所有有效前缀。 这给出了过滤新违规之前的每个序列。 
3、减去当前仓位失效的情况。 如果后面两个位置的值是`x`，那么前一个值必须足够大，使得当前位置超过其邻居的总和。 可以计算该先前值的选择数量，而无需显式存储它。 
4. 维护前一DP层的前缀和。 这些前缀和允许在恒定时间内找到所有可能的先前值的总贡献，而不是迭代所有值。 
5. 添加值为零的最终人工位置。 相同的转换处理最后一个位置，强制真正的最后一个元素满足边界条件。 

工作原理：DP 对所有序列进行计数，并精确减去包含无效位置的序列。 唯一微妙的一点是在减法过程中避免重复计算。 由于两个无效位置不能相邻，因此在从左到右的过程中可以独立处理每个无效位置。 DP 中存储的包含-排除权重捕获剩余的可能无效选择，因此以零结尾的最终状态恰好包含好序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n, k, mod):
    prev = [0] * (k + 1)
    prev[0] = 1

    pref_prev2 = [0] * (k + 1)
    pref_prev = [0] * (k + 1)

    for i in range(k + 1):
        pref_prev2[i] = 1
        pref_prev[i] = i + 1

    for pos in range(2, n + 2):
        cur = [0] * (k + 1)

        bad = 0
        for j in range(k, -1, -1):
            bad += pref_prev2[k - j - 1] if k - j - 1 >= 0 else 0
            bad %= mod
            cur[j] = (pref_prev[k] - bad) % mod

        pref_cur = [0] * (k + 1)
        pref_cur[0] = cur[0]
        for j in range(1, k + 1):
            pref_cur[j] = (pref_cur[j - 1] + cur[j]) % mod

        pref_prev2 = pref_prev
        pref_prev = pref_cur

    return cur[0] % mod

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        n, k, p = map(int, input().split())
        ans.append(str(solve_case(n, k, p)))
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```数组`pref_prev`和`pref_prev2`存储两个连续DP层的前缀和。 转换只需要这些总和，因此无需保留整个表。 

循环贯穿`n+1`因为还必须处理最后一个人工零。 最后的转变是强制执行正确的边界条件的原因。 

减法步骤使用`k - j - 1`小心。 如果该值为负数，则没有要删除的无效选择。 显式处理此边界可以避免 Python 中的负索引。 

所有计算均按模减少`p`加法和减法之后。 Python 整数不会溢出，但保持较小的值可以提高大量状态的性能。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(nk) | O(nk) | 每个`n+1`DP层处理所有`k+1`可能的值一次。 |
 | 空间| O(k) | 仅存储前两层的前缀和。 |

 约束条件`n <= 3000`和总和的界限`n^2`允许这种二次式解决方案。 该实现避免了额外的`k²`memory and keeps the actual work close to the required limit.

 ## 边缘情况

 孤立峰值情况由减法项处理。 对于序列：```
[0, 5, 0]
```中间位置被计入无效选择，因为它的邻居不能支持值`5`。 DP 在达到最终状态之前删除了此贡献。 

左边界情况：```
[1, 0, 0]
```已处理，因为额外的起始零已包含在循环中。 当处理第一个位置时，唯一可能的支持来自下一个值和外部零。 该序列被排除。 

对于全相等序列：```
[1, 1, 1]
```中间值并不违规，因为`1 <= 1 + 1`，最后的人工零检查也通过了，因为`0 <= 1 + 0`。 DP 保留此序列，以确认相等的值不会被错误地视为无效。
