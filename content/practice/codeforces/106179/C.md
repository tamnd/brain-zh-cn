 ## 解决方案
 ## 问题理解

 我们给定一个正整数`c`。 任务是构造两个正整数`a`和`b`这样它们的 XOR 值之和与`c`与它们的最小公倍数之和完全相同`c`。 

输出并不要求我们找到最佳的一对。 允许范围内满足方程的任何对都被接受。 输入包含许多独立的值`c`，对于每一个我们只需要打印一个有效的结构。 

的价值`c`至多是`10^7`，而允许的值`a`和`b`可以大到`10^17`。 这告诉我们，我们不需要寻找小的答案。 大的上限暗示预期的解决方案是建设性的。 高达`2 * 10^5`测试用例，甚至是对每个数字进行因式分解或尝试候选人`c`会太慢。 该解决方案只需为每个测试用例执行恒定量的工作。 

一个常见的错误是尝试使其中一个数字等于`c`然后随机选择另一个数字。 例如，当`c = 7`，选择`a = 7`和`b = 8`看起来很诱人，因为`8`有一个单独的位，但条件失败。 左边是`(7 xor 7) + (8 xor 7) = 0 + 15 = 15`，而右侧是`lcm(7,7) + lcm(8,7) = 7 + 56 = 63`。 问题是`8`不是的倍数`c`，所以它的LCM并没有简化。 

另一个边缘情况是当`c`已经是2的幂了。 为了`c = 8`，构造仍然必须避免重叠位。 答案`a = 8`,`b = 128`作品。 左边是`0 + 136`，右边是`8 + 128`？ 乍一看这似乎有所不同，但是 XOR 与`8`是`128 xor 8 = 136`，因此两个值相等。 重要的细节是第二个数字被移动足够的位以使两个倍数独立。 

## 方法

 蛮力方法将尝试可能的值`a`和`b`并直接检验方程是否成立。 对于每一对，我们将计算两个 XOR 运算和两个 LCM 值。 这是正确的，因为它精确地测试了定义，但搜索空间是巨大的。 即使只尝试周围的一个小范围`c`会失败，因为有效答案可能需要比`c`。 自从`c`可以出现在`2 * 10^5`测试用例中，任何对可能的候选者进行循环的方法都是不可能的。 

关键的观察结果是，如果我们选择的数字是`c`。 如果`x`是的倍数`c`， 然后`lcm(x, c) = x`。 等式变为：`(a xor c) + (b xor c) = a + b`对于任意两个数，`x + y = (x xor y) + 2 * (x and y)`。 因此，阻止 XOR 表现得像加法的唯一因素是重叠设置位。 我们需要`a`和`b`没有共同点`1`位，然后`a + b = a xor b`。 

实现这一目标的最简单方法是将一个数字作为`c`本身。 第二个数字可以是`c`向左移动足够的位置，使其位不与原始位重叠`c`。 如果移位的位长度为`c`，移位副本严格在使用的所有位之后开始`c`。 

让：`a = c`

`b = c * 2^(number of bits in c)`两个数字都是`c`，所以他们的 LCM 就是他们自己。 它们的二进制表示不共享任何设置位。 所以：`a xor c = 0`和`b xor c = b + c`左边变成`0 + b + c`，等于右侧`a + b = c + b`。

 | 蛮力 | 每个测试用例 O(range²) | O(1) | O(1) | 太慢了 |
 | 最佳 | 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 设置`a`等于`c`。 这保证了`a`是的倍数`c`， 所以`lcm(a, c)`恰好变成`a`。 还，`a xor c`变为零，删除 XOR 表达式的一侧。 
2.求出需要表示的位数`c`。 移动这个量会移动每组的位`c`超过现有的最高位，因此移位后的值不能与`c`。 
3. 构建`b`作为`c`左移位长度为`c`。 这保持`b`的倍数`c`，这意味着`lcm(b, c) = b`。 
4. 输出`a`和`b`。 自从`a`和`b`没有共享设置位，它们的总和等于它们的 XOR，这使得所需的相等性成立。 

为什么它有效：该结构保留了两个属性。 两个数字都是`c`，因此 LCM 侧减少为`a + b`。 同时，两个数字以二进制形式分开，因此与`c`其作用类似于第二个数字的加法，而第一个数字的贡献为零。 这两个事实迫使等式两边变成相同的值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []
    for _ in range(t):
        c = int(input())
        shift = c.bit_length()
        a = c
        b = c << shift
        ans.append(f"{a} {b}")
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```该解决方案独立读取每个测试用例，因为不同的值之间不存在共享状态`c`。 

价值`shift`计算使用`bit_length()`，给出最高设置位之后的位置。 例如，`7`有二进制表示`111`，所以它的位长是`3`。 变速`7`经过`3`给出`111000`，不能与原来的重叠`111`。 

该结构仅使用通过位移位乘以 2 的幂。 这些值安全地保持在以下水平`10^17`因为最大可能`c`只是`10^7`，并移动约`24`位给出了大约的值`1.6 * 10^14`。

为了`c = 7`:

 | 步骤| c | 班次 | 一个 | 乙|
 | ---| ---| ---| ---| ---|
 | 构建价值观 | 7 | 3 | 7 | 56 | 56

 二进制形式是`111`和`111000`，因此它们不重叠。 

XOR 端是：`7 xor 7 + 56 xor 7 = 0 + 63 = 63`LCM端是：`lcm(7,7) + lcm(56,7) = 7 + 56 = 63`等式成立。

 ## 边缘情况

 当`c = 1`，第一个数字变为`1`第二个数字是`2`。 这两个值具有单独的位。 方程变为`0 + 3 = 1 + 2`，所以构造仍然有效。 

什么时候`c`是 2 的幂，移位仍必须将第二个副本移到原始位之外。 为了`c = 8`，该构造给出`a = 8`和`b = 128`。 两个数字都是`8`，并且它们的设置位不同，因此 LCM 值正是数字本身。 

对于较大的值，例如`c = 10000000`，该算法不会尝试分解它或搜索模式。 它仅计算其位长度并对其进行移位。 结果值保持在允许的范围内，因为原始限制`c`足够小。
