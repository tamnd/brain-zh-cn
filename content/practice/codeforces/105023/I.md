 ## 解决方案
 ## 问题理解

 给定一条一维道路，表示为一串长度的字符串$N$。 每个字符描述一个单位单元：要么是由点表示的正常路段，要么是由星号表示的交通灯。 这些点有助于物理距离，而星号不会增加长度，而是对约束很重要的检查点。 

我们被允许移除一处交通灯。 移除它之后，我们在概念上在这条无限的道路上放置了一个“公里标记”，其中每公里都有一些固定的长度$K$以道路单位测量。 正好落在一公里边界上的交通信号灯不计入该公里的总里程中。 

要求每公里路段，最优去除一个红绿灯后，最多有$L$其余交通信号灯严格位于该路段内。 任务是选择移除，然后确定最大可能值$K$使得该条件适用于所有公里。 

核心困难在于，约束不是单个交通信号灯的局部约束，而是取决于它们在所有可能的长度滑动窗口下如何聚合$K$。 

约束条件允许$N$最多$10^6$，这排除了任何检查所有可能的段长度的解决方案$K$并重新计算违规行为$O(N)$每张支票。 一个天真的$O(N^2)$扫描是不可能的，甚至$O(N \log N)$除非每次检查都是线性的或更好，否则进行大量重新计算将是有风险的。 

边界行为出现了一个微妙的问题：交通灯恰好位于位置$x$和$x+K$两者不计入一公里内。 这会在计数窗口时产生相差一的敏感性，并且如果将边界包含在内，则天真的“间隔内恒星滑动窗口计数”方法通常会失败。 

另一个棘手的情况是交通信号灯间距不均匀。 删除一颗星可能只能修复一个“最差”的部分，但该部分取决于所选的$K$，因此瓶颈的身份变化为$K$变化。 

朴素推理的具体失败场景是：

 输入：```
N = 10, L = 1
.*.*.*.*.*
```贪婪的想法可能会假设移除任何单个恒星足以降低所有局部密度，但对于小恒星$K$许多重叠的窗口仍然超过$L$。 正确的答案取决于全局间距，而不是局部修复。 

## 方法

 蛮力策略是尝试每一个可能的公里长度$K$从$1$到$N$。 对于每个$K$，我们模拟滑动一个长度的窗口$K$穿过马路，数一下每个窗户内的红绿灯，考虑最好的办法是拆除一个红绿灯。 对于固定的$K$，这需要检查所有$O(N)$窗口位置，并且在每个位置中，我们必须跟踪删除一颗星星是否可以减少所有违规行为。 即使使用前缀和，识别最差窗口并模拟最佳去除仍然需要$O(N)$，导致$O(N^2)$最坏情况下的总工作量，远远超出了限制$N = 10^6$。 

关键的结构见解是对于固定的$K$，约束“每个长度-$K$区间最多有$L$删除一个后的星星”可以改写为：我们需要确保没有滑动窗口包含超过$L+1$原始配置中的星星，因为我们最多可以全局删除一颗星星，并且它必须修复所有违规行为。 这将问题转变为检测是否所有“坏窗口”（那些至少具有$L+2$星星）可以通过删除所有星星中的一颗星星来弥补。 

这将问题简化为交叉条件：对于给定的$K$，所有违规窗户必须至少共用一个公共交通信号灯。 如果存在这样的星星，将其移除可以同时修复所有违规行为。 

这将问题转化为决策问题$K$。 我们可以二分查找最大有效值$K$，因为如果给定$K$有效，任何更小的$K$也有效，因为缩小窗口只能减少星星数量。 

检查给定的可行性$K$，我们扫描所有窗口，使用滑动窗口维护星星计数，记录所有超过$L+1$星星，并与它们的星星索引范围相交。 如果交集非空，则存在单次移除。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(N^2)$|$O(N)$| 太慢了|
 | 二分查找+滑动窗口+交集|$O(N \log N)$|$O(N)$| 已接受 |

 ## 算法演练

 我们重新制定固定的决策检查$K$，然后将其嵌入到二分搜索中$K$。 

### 1. 对答案进行二分搜索

 我们维持一个搜索范围$K$。 对于每个中点$K$，我们测试一下是否可行。 如果可行，我们尝试更大的值； 否则我们会缩小范围。 这是可行的，因为可行性是单调的$K$。 

单调性成立是因为增加$K$仅增加或保留每个窗口的星星数量。 

### 2. 星星位置上的滑动窗口

 我们预处理所有交通灯的位置。 对于给定的$K$，我们在这些位置上滑动一个窗口来计算每个间隔内有多少颗星星$[i, i+K)$。 

我们不扫描整个字符串，而是在星星位置上维护两个指针，这与星星的数量呈线性关系。 

此步骤识别所有“坏窗口”，这意味着窗口至少包含$L+2$星星。 

### 3.可移动星的轨道约束

 对于每个坏窗口，我们记录其中有哪些星星。 关键要求是每个坏窗口中都存在一颗星星。 

我们将允许移除位置的交集维护为索引范围。 每个坏窗口都会产生一个约束：可移动的星星必须位于该窗口的星星集中。 由于星星是有序的，每个窗口对应于星星索引数组中的一个连续段，因此交集减少到维护全局左边界和右边界。 

如果最后交叉点是空的，则没有任何一次删除可以修复所有违规行为。 

### 4. 可行性决策

 如果没有坏窗口，则配置已经有效。 如果存在坏窗口但它们的交集非空，我们可以删除一颗星来解决所有这些问题。 否则，当前$K$无效。 

### 为什么它有效

 正确性取决于以下事实：每个违规都被定位到至少具有以下特征的窗口：$L+2$星星，并且删除违规窗口外的星星不会影响它。 因此，当且仅当存在参与每个违规窗口的恒星时，单次删除就足够了。 滑动窗口确保我们枚举所有违规行为，并且交叉条件确保它们之间的全局一致性。 然后二分查找找到最大的$K$满足这个可行性条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, L = map(int, input().split())
    s = input().strip()

    stars = [i for i, c in enumerate(s) if c == '*']
    m = len(stars)

    if m == 0:
        print(n)
        return

    def check(k):
        if m <= L + 1:
            return True

        bad_intervals = 0
        left_ptr = 0

        # intersection over star indices [lo, hi]
        lo, hi = 0, m - 1

        for r in range(m):
            while stars[r] - stars[left_ptr] + 1 > k:
                left_ptr += 1

            cnt = r - left_ptr + 1
            if cnt >= L + 2:
                bad_intervals += 1
                lo = max(lo, left_ptr)
                hi = min(hi, r)

        if bad_intervals == 0:
            return True

        return lo <= hi

    # binary search answer
    ans = 1
    lo, hi = 1, n

    while lo <= hi:
        mid = (lo + hi) // 2
        if check(mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现将道路压缩为星形位置，因此窗口计数完全忽略点。 滑动窗口仅在星星列表上运行，这对于$O(N)$每项检查的行为。 

可行性函数跟踪是否存在任何违规窗口，并同时维护所有此类窗口中出现的星形索引的交集。 如果交叉点在任何时候崩溃，我们知道没有任何一次删除可以解决该交叉点的所有违规问题$K$。 

二分搜索包装该谓词并提取最大有效公里长度。 

## 工作示例

 ### 示例 1

 输入：```
15 2
*...*.*..*...*.
```我们测试增加的可行性$K$。 对于一个小$K$，许多窗口包含多个$L+1 = 3$星，产生重叠的坏间隔。 

| 步骤| 窗口范围 | 星星数 | 窗户坏了？ | 交叉点[lo, hi] |
 | ---| ---| ---| ---| ---|
 | 1 | [0, 4] | 2 | 没有 | [0, 3] |
 | 2 | [1, 5] | 2 | 没有 | [0, 3] |
 | 3 | [0, 8] | 4 | 是的 | [1, 2] |
 | 4 | [4, 12] | 4 | 是的 | [1, 1] |

 交集缩小为单个星形索引，这意味着删除该星形可以修复所有违规窗口。 直到$K = 7$，超出这个范围窗口就会变得太宽而无法控制。 

### 示例 2

 输入：```
10 1
*.*.*.*.*
```为了$K = 1$，每个窗口最多包含一颗星，因此删除后它是平凡有效的。 作为$K$增加时，多个星星进入每个窗口，迅速产生重叠的违规行为，其交叉点变为空，这表明没有单一的删除可以修复所有这些违规行为。

 ## 边缘情况

 一个重要的边缘情况是当数量少于$L+2$总共有红绿灯。 在这种情况下，每个窗口在移除任何一盏灯后都会自动满足约束，因此正确的答案很简单$N$。 该算法通过返回 true 在可行性检查中立即处理此问题。 

另一种情况是交通信号灯极其稀疏时。 例如，如果星星出现在相距较远的位置，则每个可行的$K$变得很大，因为窗口很少积累足够的星星来违反限制。 恒星位置上的滑动窗口自然地反映了这一点，因为窗口计数条件永远不会达到$L+2$。 

当违反窗口重叠但不共享公共星时，会出现更微妙的情况。 在这种情况下，交集范围就会崩溃。 检查功能通过维护的功能精确捕获这一点$[lo, hi]$间隔。 如果它变空，它正确地拒绝候选人$K$，即使每个单独的窗口似乎都可以单独修复。
