 ## 解决方案
 ## 问题理解

 我们有一组放置在一维线上的卡车。 每辆卡车都从不同的位置开始，并以固定的速度永远移动。 每当两辆卡车同时在同一点相遇时，它们就会发生碰撞，并且它们不会发生物理相互作用，而只是交换速度。 由于所有卡车都具有相同的质量，因此这种交换规则使系统的行为就像卡车彼此经过但交换身份一样。 

任务不是明确地模拟运动，而是计算总共发生了多少碰撞事件。 两辆卡车之间的碰撞事件对答案有贡献，但多辆卡车同时相遇时除外，在这种情况下，其中所有无序对都被计为碰撞。 如果该过程导致无限多次碰撞，我们必须报告-1。 

约束表明卡车数量最多为 5000 辆，因此任何检查所有卡车对的方法都是边界性的，但在 O(N^2) 中仍然可行。 任何涉及连续时间事件模拟的事情都会太慢或在数值上脆弱，因为碰撞时间可能是分数并且许多事件可能级联。 

一个天真的但重要的观察是，如果我们忽略身份交换，两辆卡车最多可以碰撞一次，因为碰撞后它们实际上会继续碰撞，就好像它们穿过彼此一样。 唯一的复杂性是，我们必须正确计算“有效运动方向”上的反转次数，并处理多辆卡车同时相遇的退化情况。 

当多辆卡车具有相同的速度并且最初以相互冲突的方式排序时，就会出现微妙的边缘情况。 如果一辆较快的卡车在一辆较慢的卡车后面起步，它们只会相遇一次； 如果一辆较慢的卡车在一辆较快的卡车后面启动，他们永远不会相遇。 然而，如果速度相等而位置不同，它们永远不会碰撞。 主要危险是错误地假设单调性而不考虑相等的速度组。 

另一个重要的极端情况是无限碰撞。 当配置允许永久弹跳行为而没有进展时，就会发生这种情况，但在线上的这种特定的等质量交换模型中，只有当存在事件无限重复的病态对称情况时才会出现无限碰撞，这实际上减少了检测简并事件，其中碰撞事件不会降低系统复杂性。 我们稍后会对此进行精确说明。 

## 方法

 暴力破解的想法是模拟每一对卡车，计算它们是否相遇，如果相遇则算一次碰撞。 对于两辆卡车 i 和 j，我们比较位置和速度并求解交叉时间：$$x_i + v_i t = x_j + v_j t$$产生：$$t = \frac{x_j - x_i}{v_i - v_j}$$如果 t 为正，我们就算碰撞。 

这种方法可以正确计算每一对是否相遇。 然而，它在两个方面失败了。 首先，它忽略了多卡车同时碰撞，其中 k 辆卡车同时相遇，我们必须计算 k(k-1)/2，而不是单独的成对事件。 其次，天真的配对计数假设独立，但身份交换意味着我们必须小心我们是否在跟踪物理交叉点或标记的交互。 幸运的是，在这个等质量交换模型中，只要我们正确处理同时分组，计算成对交叉点仍然可以给出正确的总碰撞计数。 

瓶颈很简单：有 O(N^2) 对，最多约为 2500 万个。 仅当每次检查的复杂度为 O(1) 时，这在 Python 中才是可接受的，因此主要挑战是稳健地对同时发生的碰撞时间进行分组。 

关键的见解是将 i 和 j 之间的每次碰撞视为一个时间事件，按精确的理性时间进行分组，然后计算有多少对共享该时间。 我们不是模拟运动，而是枚举所有成对碰撞时间，将它们分组，并对每个桶的贡献求和。 

这将问题简化为计算 O(N^2) 有理时间并聚合它们。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O（事件日志事件）最坏情况无界 | O(N) | 太慢/脆弱|
 | 成对时间分桶 | O(N^2) | O(N^2) | O(N^2) | O(N^2) | 已接受 |

 ## 算法演练

 我们继续计算所有卡车对的碰撞时间并对相同的时间进行分组。 

1. 对于每对卡车 i 和 j，假设 i 位于 j 的左侧（如果需要按位置交换）。 这避免了双重处理并确保一致的标志处理。 原因是碰撞方向纯粹由一维中的相对顺序决定。 
2. 计算相对速度。 如果左边的卡车不比右边的卡车快，他们永远不会相遇，所以跳过这一对。 唯一有意义的碰撞发生在左边的卡车速度更快并追上时。 
3. 将碰撞时间计算为约分式：$$t = \frac{x_j - x_i}{v_i - v_j}$$使用 gcd 归约将其存储为标准化整数对，而不是浮点数。 这可以避免错误地合并或拆分碰撞事件的精度错误。 
4. 使用以减少时间的（分子，分母）为键的哈希图来计算在该确切时刻有多少对发生冲突。 
5. 处理完所有对后，每个桶对应于每个条目恰好涉及两辆卡车的同时碰撞事件。 然而，多对可能共享相同的时间，这意味着 k 辆卡车相遇。 对于具有 m 对的桶，我们必须恢复 k 使得：$$m = \frac{k(k-1)}{2}$$然后直接加上m，因为每一对都是碰撞。 
6. 对所有存储桶贡献求和。 

一个关键细节是，我们依赖于这样一个事实：等质量交换动力学保留独立于身份交换的碰撞时间集，因此成对的几何交集完全确定了答案。 

### 为什么它有效

 每次碰撞对应于时间位置平面中两个线性轨迹的唯一交点。 由于交换速度不会改变几何路径，因此每个交点都是初始数据所固有的。 按时间分组可以正确处理多卡车同时会议，因为所有参与的卡车必须共享相同的成对交叉时间，从而在该时间戳处强制形成派系结构。 计算每个团中的所有对完全符合所需的 k(k-1)/2 规则。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import defaultdict
from math import gcd

def norm_num_den(num, den):
    if den < 0:
        num = -num
        den = -den
    g = gcd(abs(num), abs(den))
    return num // g, den // g

def solve():
    n = int(input())
    trucks = []
    for _ in range(n):
        x, v = map(int, input().split())
        trucks.append((x, v))

    events = defaultdict(int)

    for i in range(n):
        xi, vi = trucks[i]
        for j in range(i + 1, n):
            xj, vj = trucks[j]

            if xi == xj:
                continue

            if xi < xj:
                left_x, left_v = xi, vi
                right_x, right_v = xj, vj
            else:
                left_x, left_v = xj, vj
                right_x, right_v = xi, vi

            if left_v <= right_v:
                continue

            num = right_x - left_x
            den = left_v - right_v

            if den == 0:
                continue

            t = norm_num_den(num, den)
            events[t] += 1

    ans = 0
    for cnt in events.values():
        ans += cnt

    print(ans)

if __name__ == "__main__":
    solve()
```该实现迭代所有卡车对并强制执行一致的左右顺序，以便仅考虑向前移动的追赶者。 冲突时间存储为简化分数，以确保相同的时间映射到相同的哈希键。 

一个常见的陷阱是使用浮点除法来计算时间。 由于精度错误，这会错误地合并或分离事件。 另一个微妙之处是确保正确处理方向：只有较快的左侧卡车追上较慢的右侧卡车才会产生有效的碰撞。 

最后，请注意，我们从未同时显式重建 k 辆卡车组。 相反，将每个时间段内的所有成对碰撞相加就已经产生了所需的 k(k-1)/2 总数。

 ## 边缘情况

 一个关键的边缘情况是所有卡车具有相同的速度。 在这种情况下，不存在相对运动，因此任何一对都不会相遇。 该算法正确地跳过所有对，因为条件`left_v <= right_v`消除它们。 

另一个边缘情况是严格排序且速度严格递减。 在这里，每一对都会发生碰撞，而且通常是在同一时间发生碰撞。 分桶逻辑确保同时合并所有交叉点，从而隐式生成正确的 k(k-1)/2 贡献。 

最后一个微妙的情况是速度非常大，高达 10^9。 如果不减少分数，碰撞时间可能会溢出或失去精度。 gcd 归一化确保结构上相同的时间始终被合并，无论大小如何。
