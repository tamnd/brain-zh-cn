 ## 解决方案
 ## 问题理解

 我们得到了多组卡车长度，我们想用其中的一些长度组装一个特殊的“树形结构”。 该结构有一个垂直的脊柱，由一层一层堆叠的卡车组成。 在该脊柱中的每两辆连续卡车之间，有一个分支级别：在该级别上，我们必须附加两辆长度相等的额外卡车，一辆在左侧，一辆在右侧。 

脊柱卡车的垂直顺序是灵活的，因为我们可以自由选择哪些长度去哪里，但是分支对引入了一个约束：分支长度必须严格遵守沿着脊柱的单调规则，较长的分支放置在较低的位置，较短的分支放置在较高的位置。 这消除了任意混合分支大小的任何优势； 一旦选择了分支长度，它们总是可以通过排序一致地排列。 

我们可以使用给定卡车的任何子集。 目标是最大限度地增加垂直脊柱中的卡车数量，因为这决定了整个结构的高度。 

约束条件很大，卡车数量可达 200,000 辆，长度可达 10^9。 这立即排除了任何尝试所有子集或显式模拟结构构建的方法。 任何解决方案在不同值的数量上都必须本质上是线性的或线性对数的，因为计算频率是不可避免的。 

一些边缘情况值得牢记。 如果所有卡车都是不同的，则不存在分支对，因此该结构退化为大小为 1 的脊柱。如果所有卡车都相同，我们可以形成许多分支对，但限制因素是在给定项目总数的情况下我们可以支持多少个完整“级别”。 如果有很多对但没有足够的剩余单对，该结构仍然会失败，因为每个主干节点都会消耗一辆独立于分支使用情况的卡车。 

## 方法

 强力解释将尝试确定哪些卡车子集形成主干，哪些卡车子集形成分支对，然后检查我们是否可以按有效顺序将等长对分配给每个级别。 这很快就变成了组合：选择大小为 k 的脊柱已经有很多可能性，对于每个这样的选择，我们需要验证是否可以从剩余的项目中形成 k−1 个有效的等长对，同时尊重排序约束。 即使我们避免排列并且只考虑频率分配，将值拆分为脊柱元素和配对元素的方法数量也会随着 N 呈指数增长。 

关键的观察结果是，该结构实际上对“哪些确切值”进入脊柱与超出简单计数约束的对并不敏感。 分支长度的排序条件始终可以通过对选定的线对长度进行排序来满足，因此一旦我们知道每种尺寸有多少对，它就不会限制可行性。 

这将问题简化为计数分配任务。 每个主干尺寸为 k 的有效结构都需要 k 个主干卡车和 k−1 个分支对。 每个分支对消耗两个相同长度的卡车，因此重要的是我们可以从多重集中形成多少个不相交的对。 一旦我们知道了可用对的总数，我们只需要确保我们有足够的物品来支撑脊柱。 

因此，问题分解为两个约束：可用对的数量必须至少为 k−1，并且在使用这些对后，剩余卡车的总数必须至少为 k。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集构造 | 指数| O(N) | 太慢了|
 | 频率计数+约束| O(N) | O(N) | 已接受 |

 ## 算法演练

1. 计算每个长度在输入中出现的次数。 这是必要的，因为配对仅取决于频率，而不取决于身份。 
2. 对于每个不同的长度，计算它可以贡献多少个不相交对，即floor(count / 2)。 将这些值相加即可获得可用对 P 的总数。 
3. 观察到高度为 k 的脊椎恰好需要 k−1 个分支层，因此我们必须使 P ≥ k−1。 这给出了约束 k ≤ P + 1。 
4. 另请注意，每个主干节点使用一辆卡车，每个分支对使用两辆卡车。 脊柱尺寸为 k 的结构恰好消耗 2(k−1) + k = 3k−2 辆卡车。 因此我们必须有 3k−2 ≤ N，这意味着 k ≤ (N+2) // 3。 
5. 结合两个约束并取最大可行 k，即 min(P + 1, (N + 2) // 3)。 

### 为什么它有效

 一旦我们确定了 k，我们就不再决定任何结构性的事情。 我们只需要知道多重集是否能够提供足够的独立“资源”：k 个单个项目用于脊柱，k−1 对相等的项目用于分支。 对分支长度的单调排序要求永远不会限制可行性，因为任何 k−1 个所选对值的多重集都可以排序以满足条件。 这意味着可行性完全取决于计数，而不是排列，并且这两个不等式捕获了所有必要的限制。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    freq = {}
    for x in arr:
        freq[x] = freq.get(x, 0) + 1

    pairs = 0
    for c in freq.values():
        pairs += c // 2

    ans = min(pairs + 1, (n + 2) // 3)
    print(ans)

if __name__ == "__main__":
    solve()
```实现首先在所有卡车长度上构建频率图，因为配对仅取决于相同的值。 然后，它计算通过将每个频率桶的楼层除以二求和可以形成多少个不相交对。 最后，它直接应用导出的约束。 

一个微妙的点是，我们从未明确构建哪些卡车进入脊柱或成对。 这是不必要的，因为证明仅显示计数物质，并且任何有效的计数分配都可以通过从每个频率桶中选择任意代表来实现。

```我们计算频率：1→2、2→3、3→1、4→1、5→1。 这给出pair = 1（来自值1）+ 1（来自值2）= 2。 

我们现在评估 k 的约束：

 | k | P ≥ k−1 | 3k−2 ≤ 8 | 3k−2 ≤ 8 有效|
 | ---| ---| ---| ---|
 | 1 | 是的 | 是的 | 是的 |
 | 2 | 是的 | 是的 | 是的 |
 | 3 | 是的 | 是的 | 是的 |

 所以答案是3。 

此跟踪显示，即使存在多个值，也只有可用对的数量限制了可以支持的分支级别数。 

### 示例 2

 输入：```
5
1 2 3 4 5
```所有频率均为 1，因此 P = 0。 

| k | P ≥ k−1 | 3k−2 ≤ 5 | 3k−2 ≤ 5 有效|
 | ---| ---| ---| ---|
 | 1 | 是的 | 是的 | 是的 |
 | 2 | 没有| 是的 | 没有|

 答案是1。 

这演示了不可能配对的情况，迫使结构退化为单节点脊柱。

 ## 边缘情况

 关键的边缘情况是输入有许多重复项集中在一个值中。 例如，`1 1 1 1 1 1`。 这里我们有 3 对可用，所以 P = 3。公式给出 k = min(4, (6+2)//3 = 2)，所以 k = 2。即使有很多对，项目总数对书脊大小的限制比对可用性更严格。 

另一个边缘情况是根本没有重复项。 为了`1 2 3 4`，P = 0，因此无论 N 如何，k = 1。该算法正确地将结构折叠为单个脊柱元素，因为无法形成分支级别。 

这些案例证实，对可用性和总资源限制这两个约束都是独立必要的，并且一起就足够了。
