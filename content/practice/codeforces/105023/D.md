 ## 解决方案
 ## 问题理解

 每架飞机在从到达时间到起飞时间的连续时间间隔内占据一个登机口。 当它出现在机场时，它会阻挡一个登机口，因此重叠的间隔对应于同时登机口的使用。 

对于给定的查询间隔$[l, r]$，我们被要求仅考虑该时间窗口内相关的平面。 如果一架飞机在机场的存在与查询间隔重叠，并且在机场内部的某个时间处于“活动”状态，则该飞机会在查询期间造成拥堵，并且在边界处有一个特殊规则：飞机恰好在$l$或者$r$被排除在外，而飞机恰好抵达$l$或者$r$都包括在内。 

每个查询的任务是确定间隔内任意时刻同时存在的最大飞机数量$[l, r]$，因为该最大值等于避免冲突所需的最小门数。 

约束条件$N \le 10^5$立即排除任何通过扫描所有平面来重新计算每个查询重叠的解决方案。 甚至$Q \le 50$不保存二次或$N \log N$每个查询方法，因为$50 \cdot 10^5$每个查询逻辑最多仍然只允许线性或近线性。 

微妙的边缘情况来自边界规则。 如果飞机恰好在$l$，它不算数，即使像这样天真的重叠检查$a_i \le r$和$d_i \ge l$会错误地包含它。 

例如，如果一个平面有间隔$[5, 10]$一个查询是$[10, 12]$，简单的交叉点检查会将其视为在 10 处处于活动状态，但该语句排除了边界处的偏离，因此它根本不应该起作用。 

另一个边缘情况是查询恰好在大量到达时开始或结束。 到达边界的人数会被计算在内，因此间隔恰好从$l$仍必须包含在活动集中。 

## 方法

 回答每个查询的直接方法是模拟时间。 对于每个查询，我们可以迭代所有平面并检查它们的间隔是否与边界规则下的查询间隔重叠，然后计算所有相关时间的最大重叠数。 

这是正确的，但价格昂贵。 对于每个查询，我们可能会检查$10^5$间隔，然后确定时间上的重叠，从而大致得出$O(NQ)$只是为了过滤，如果我们尝试连续扫描时间，情况会更糟。 隐藏的成本是检测最大重叠需要推理事件排序或随时间的扫描，这使得天真的每个查询模拟太慢。 

关键的观察是每个查询只关心固定窗口内活动间隔的最大数量。 这是一个经典的转换：我们不再考虑连续时间，而是将每个飞机转换为两个事件，一个到达事件和一个出发事件，然后将问题简化为对排序事件时间进行前缀计数。 

一旦事件被排序，我们就可以构建一个前缀和数组，表示每个事件边界有多少个平面处于活动状态。 然后，查询简化为在有限的事件索引范围内查找最大前缀和值。 这是对静态数组的范围最大查询，可以用稀疏表或线段树来回答。 

因为$Q \le 50$，我们可以全局进行一次预处理，然后通过将其时间范围映射到排序事件列表中的索引并采用范围最大查询来回答每个查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(NQ)$到$O(N^2)$取决于方法|$O(1)$到$O(N)$| 太慢了|
 | 扫一扫+RMQ |$O(N \log N + Q \log N)$|$O(N \log N)$| 已接受 |

 ## 算法演练

 我们将每个间隔转换为两个事件，但我们必须仔细遵守边界规则。 

1. 将每架飞机表示为到达时间的 +1 事件$a_i$以及出发时的 -1 事件$d_i$。 通过在排序中正确处理排序，我们将到达视为包容性，将出发视为排除。 这确保了在精确的边界时间正确计数。 
2. 将所有事件按时间排序，如果两个事件时间相同，则先处理到达事件，再处理出发事件。 这种排序编码了以下规则：到达边界的情况被计算在内，而出发的情况则不被计算在内。 
3. 扫描已排序的事件并计算前缀和数组，其中每个位置存储处理该事件后活动平面的数量。 这给出了随时间变化的分段常数函数。 
4. 对于每个不同的事件时间，存储相应的前缀和值。 这将时间线最多压缩为$2N$点。 
5. 在此前缀和数组上构建范围最大结构，以便我们可以有效地查询任何连续段上活动平面的最大数量。 
6. 对于每个查询$[l, r]$，找到第一个事件索引，其时间为$\ge l$以及时间为的最后一个事件索引$\le r$。 它们定义与查询窗口相交的时间线段。 
7. 使用范围最大结构来计算该段上的最大前缀和，从而给出查询的答案。 

其工作原理取决于扫描线的结构。 在连续的事件时间之间，活动平面的数量不会改变，因此任何查询间隔内的最大值必须出现在间隔内的某个事件边界处。 对事件进行排序后的前缀和正确地表示了每个此类边界处的活动平面的数量，因此在限制范围内取最大值可以准确地捕获内部的峰值拥塞$[l, r]$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SparseTable:
    def __init__(self, arr):
        n = len(arr)
        self.n = n
        self.log = [0] * (n + 1)
        for i in range(2, n + 1):
            self.log[i] = self.log[i // 2] + 1

        k = self.log[n] + 1
        self.st = [[0] * n for _ in range(k)]
        self.st[0] = arr[:]

        j = 1
        while (1 << j) <= n:
            i = 0
            while i + (1 << j) <= n:
                self.st[j][i] = max(self.st[j - 1][i],
                                     self.st[j - 1][i + (1 << (j - 1))])
                i += 1
            j += 1

    def query(self, l, r):
        j = self.log[r - l + 1]
        return max(self.st[j][l], self.st[j][r - (1 << j) + 1])

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    d = list(map(int, input().split()))

    events = []
    for i in range(n):
        events.append((a[i], 1))
        events.append((d[i], -1))

    events.sort(key=lambda x: (x[0], -x[1]))

    times = []
    active = []
    cur = 0

    for t, v in events:
        cur += v
        times.append(t)
        active.append(cur)

    st = SparseTable(active)

    def lower_bound(x):
        lo, hi = 0, len(times)
        while lo < hi:
            mid = (lo + hi) // 2
            if times[mid] >= x:
                hi = mid
            else:
                lo = mid + 1
        return lo

    def upper_bound(x):
        lo, hi = 0, len(times)
        while lo < hi:
            mid = (lo + hi) // 2
            if times[mid] > x:
                hi = mid
            else:
                lo = mid + 1
        return lo - 1

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        L = lower_bound(l)
        R = upper_bound(r)
        if L > R:
            out.append("0")
        else:
            out.append(str(st.query(L, R)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```事件排序步骤是强制边界正确性的地方。 按时间排序并将到达时间安排在出发时间之前，确保及时$t$，在同一时间戳的任何删除之前，到达的航班都包含在内。 

前缀累积在每个事件之后构建了活动平面的确切数量，因此每个索引对应于一个稳定状态。 然后，稀疏表允许对任何段进行恒定时间最大查询。 

二分搜索精确地隔离了事件时间线与查询间隔相交的部分，确保我们只考虑发生在$[l, r]$。 

## 工作示例

 ### 示例 1

 输入：```
N = 5, Q = 2
a = [2, 7, 4, 5, 9]
d = [8, 11, 5, 8, 16]
queries:
[1, 10]
[8, 14]
```排序后的事件：```
(2,+1), (4,+1), (5,+1), (7,+1), (8,-1), (8,-1), (9,+1), (11,-1), (16,-1)
```前缀活跃计数：

 | 活动索引 | 时间 | 改变 | 活跃|
 | ---| ---| ---| ---|
 | 0 | 2 | +1 | 1 |
 | 1 | 4 | +1 | 2 |
 | 2 | 5 | +1 | 3 |
 | 3 | 7 | +1 | 4 |
 | 4 | 8 | -1 | 3 |
 | 5 | 8 | -1 | 2 |
 | 6 | 9 | +1 | 3 |
 | 7 | 11 | 11 -1 | 2 |
 | 8 | 16 | 16 -1 | 1 |

 询问$[1, 10]$选择覆盖时间 2 到 9 的索引，给出 max active = 4。 

查询$[8, 14]$选择 8 到 11 左右的索引，给出 max active = 3。 

这证实了该算法正确地捕获了受限窗口内而不是全局的峰值重叠。 

### 示例 2

 输入：```
N = 3, Q = 1
a = [1, 3, 5]
d = [4, 6, 8]
query: [4, 4]
```在时间 4 时，第二个平面仍然处于活动状态，因为它在 6 点出发，而第一个平面恰好在 4 点出发，并且被边界规则排除。 

查询时的活动平面 = 1。 

事件表示确保 4 点到达的航班包含在 4 点出发之前，因此前缀状态可以正确反映单个活动间隔。

 ## 边缘情况

 关键的边缘情况是飞机恰好在查询边界处离开。 对于输入：```
a = [1], d = [5], query = [5, 5]
```正确的输出是 1，因为根据解释，平面仍然存在，但不包括 5； 根据给定的规则，5 点出发的航班被排除在外，因此飞机在 5 点没有贡献。扫线排序可确保在考虑到达时间后应用时间 5 的 -1 事件，从而防止错误包含。 

当多个事件共享相同的时间戳时，会出现另一种边缘情况。 例如：```
a = [5, 5], d = [10, 10], query = [5, 5]
```两架飞机均在 5 点到达，因此必须对两架飞机进行计数，得到 2。在出发之前对到达进行排序可确保在当时进行任何减法之前前缀达到 2。
