 ## 解决方案
 ## 问题理解

 我们有一系列面粉厂。 每个磨坊都有两个属性：每小时可以加工多少小麦以及距离加工多少小时。 将小麦运送到磨坊并将面粉运回需要两倍于给定运输时间的时间。 如果工厂收到`x`公斤，研磨部分需要`x / p`小时，地点`p`是它的处理速度。 

任务是在各个磨坊之间分配小麦总量，以便尽早返回最后一批小麦。 输出是最短完成时间，具有浮点精度。 

输入尺寸很大。 最多可以有`100000`工厂，因此检查每个可能的分布是不可能的。 小麦用量可达`10^9`，并且速度和行程时间也可能非常大，因此解决方案需要对答案进行对数搜索，而不是模拟过程。 一个接近的解决方案`O(n)`或者`O(n log C)`需要，其中`C`是可能答案的范围。 

一些边缘情况很容易被忽略。 加工速度非常高的磨机可能由于运输时间的原因，早期仍无法发挥作用。 例如：```
2 100

1000 100
1 1
```第二台磨机的加工速度足够快，但仅第一批货物就需要 200 小时才能开始研磨。 仅比较加工率的粗心解决方案可能会选择错误的磨机。 

另一种情况是几家工厂同时完成生产。 例如：```
3 7

1 1
1 1
1 1
```答案不是`7`，因为小麦可以分成三等份。 每个磨坊处理`7/3`公斤，要求`7/3`磨削时间加`2`旅行时间，给出：```
13/3 = 4.333333333333
```将所有小麦分配给一个磨坊的解决方案错过了并行处理。 

## 方法

 直接的方法是决定每个工厂接收多少小麦。 对于选定的金额`x_i`, 磨机`i`之后完成：```
2 * t_i + x_i / p_i
```小时。 目标是最小化这些值的最大值。 蛮力方法会尝试在磨坊之间分配不同的小麦，并保持最佳的完成时间。 即使仅表示整数千克分裂也已经给出了巨大的可能性。 如果有`n`磨坊和`w`千克，可能的分布数量是以下组合的数量级`w + n`，当两个值都很大时，这是完全不可行的。 

有用的观察是颠倒问题。 不要问“最快的时间表是什么？”，而是问“我们是否有`T`可用的时间，我们能完成多少小麦？”

 对于固定的完成时间`T`，磨机只能在往返运输时间过后才能使用。 如果`T <= 2*t_i`，该磨坊无法完成任何小麦。 否则，剩余时间为：```
T - 2*t_i
```工厂可以加工：```
p_i * (T - 2*t_i)
```公斤。 

将其添加到所有磨坊中即可得出按时间可以完成的小麦总量`T`。 该值仅在以下情况下增加`T`增加，所以我们可以二分查找最小的`T`可以处理所有`w`公斤。 

暴力破解会失败，因为它试图自行构建发行版。 上述观察消除了了解分布的需要。 我们只需要测试在某个截止日期之前是否存在足够的容量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 可能的分布数量呈指数增长 | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n log C) | O(n log C) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取所有磨机并存储其加工率和行程时间。 搜索过程中唯一需要的信息是每个工厂为候选完成时间贡献了多少产能。 
2. 找到答案的下限和上限。 下限可以为零。 对于上限，重复将值加倍，直到该值足够大，到那时每个磨坊都可以加工所有小麦。 这避免了依赖于未知的最大值。 
3、结束时间二分查找`T`。 对于中间点，计算可加工的小麦总量。 
4. 对于每个工厂，仅在以下情况下添加其贡献：`T > 2*t_i`。 其贡献是`p_i * (T - 2*t_i)`。 如果累计容量达到`w`，这个时候是可行的。 
5. 如果当前时间可行，则搜索较小的一半，因为更早的完成时间也可能有效。 否则，搜索较大的一半。 
6. 经过足够的迭代后，输出下界。 浮点二分查找不需要精确的停止点，因为所需的误差仅为`10^-6`。 

为什么有效：对于任何固定时间`T`，每个工厂都有在该截止日期之前可以完成的最大小麦数量。 任何有效的时间表完成时间`T`不能超过这个容量，并且这个容量内的任何数量都可以在工厂之间独立分配。 所以，`T`当这些能力的总和至少是小麦总量时，这就是可能的。 由于可行性是单调的，二分查找找到尽可能小的完成时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, w = map(int, input().split())
    mills = []

    for _ in range(n):
        p, t = map(int, input().split())
        mills.append((p, t))

    def can(x):
        total = 0.0
        for p, t in mills:
            remain = x - 2.0 * t
            if remain > 0:
                total += p * remain
                if total >= w:
                    return True
        return False

    lo = 0.0
    hi = 1.0

    while not can(hi):
        hi *= 2.0

    for _ in range(100):
        mid = (lo + hi) / 2.0
        if can(mid):
            hi = mid
        else:
            lo = mid

    print("{:.12f}".format(hi))

if __name__ == "__main__":
    solve()
```这`can`功能是解决方案的核心。 它回答了特定的截止日期是否足够。 对于每个工厂来说，运输时间消耗`2*t`小时优先，所以研磨时间只是剩下的部分。 容量计算使用浮点值，因为答案不一定是整数。 

上限是动态构建的。 加倍可以避免猜测最大答案，并保证二分搜索从一个不可能的端点和一个可能的端点开始。 

二分查找使用固定次数的迭代，而不是使用微小的间隔进行比较。 大约 100 次迭代远远超出了双精度所需的量，并且它使实现变得简单。 

容量可能会变得非常大，但 Python 整数和浮点值可以安全地处理所需的范围。 早日回归于`can`避免在小麦达到目标数量后进行不必要的工作。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log C) | O(n log C) | 每次二分搜索迭代都会扫描所有工厂，大约使用 100 次迭代 |
 | 空间| O(n) | 工厂列表已存储 |

 输入限制为`100000`米尔斯每次迭代都需要进行线性扫描。 固定的 100 次二分搜索迭代可提供大约 1000 万次简单操作，这非常合适。

 ## 边缘情况

 对于行程时间较长的情况：```
2 100

1000 100
100 1
```第一个磨机要经过 200 小时才能做出贡献。 第二台磨机可加工`100 * (T - 2)`两小时后公斤。 最短可行时间为`3`，它有整整一小时的时间来加工小麦。 

对于同等磨坊情况：```
3 7

1 1
1 1
1 1
```在候选时间`4.333333333333`, 每个工厂都有`2.333333333333`数小时的研磨时间。 每人贡献那么多小麦，加起来就达到了7公斤。 该算法自然会发现这一点，因为它只检查总容量，而不是特定的分配。 

对于单个工厂：```
1 1

1 1
```工厂需要两个小时的运输时间和一小时的研磨时间。 容量检查恰好在某个时间变为正确`3`，因此二分查找会返回正确的值，而不需要任何特殊情况。
