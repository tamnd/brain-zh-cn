 ## 解决方案
 ## 问题理解

 任务要求我们表达一个正整数`n`作为立方之和。 我们必须打印一个整数列表，每个整数之间`-10000`和`10000`，其立方加起来正好等于`n`。 接受任何有效的分解，并且打印的术语数量不能超过`10000`。 

输入是表示目标值的单个整数。 输出首先给出分解中有多少个整数，然后是这些整数本身。 

约束条件是`n`至多是`9241`是关键细节。 直接构造可以利用以下事实：`1³ = 1`。 如果我们打印`n`号码的副本`1`，它们的立方总和为`n`。 由于最大可能`n`是`9241`，这最多产生`9241`条款，这是安全低于限制`10000`。 

这立即排除了对数论搜索、动态规划或预计算的需要。 任何试图找到更短表示的方法都在解决比所提出的问题更难的问题。 

主要的边缘情况与输出大小和处理最小可能值有关。 为了`n = 1`，输出应包含一项：```
Input
1

Output
1
1
```粗心的实现可能会尝试初始化一个空答案，并忘记为最小值添加任何内容。 

对于最大允许值：```
Input
9241

Output
9241
1 1 1 ... 1
```和`9241`的副本`1`，答案仍然有效。 如果假设项数很小的解决方案尝试创建许多不必要的值，则可能会意外违反输出限制。 

另一个常见的错误是打印立方体而不是原始整数。 例如，对于`n = 3`，正确的输出是：```
Input
3

Output
3
1 1 1
```因为要检查的总和是`1³ + 1³ + 1³`， 不是`1 + 1 + 1`作为简单值。 

## 方法

 蛮力解释是搜索数字的组合，其立方相加`n`。 人们可以尝试每一种可能的立方体值，使用递归，或者根据可能的总和构建动态规划解决方案。 这些方法是正确的，因为它们探索了有效的分解，但它们完全忽略了慷慨的输出限制。 与有限的范围相比，搜索空间是巨大的`n`。 

暴力搜索会失败，因为它花费时间来发现已经以最简单的形式存在的分解。 观察结果表明`1³ = 1`完全改变了问题。 由于目标永远不会大于`9241`, 重复`1`确切地`n`times 始终满足总和条件和最大项数条件。 

最优解就是输出`n`的副本`1`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 取决于搜索策略，可能呈指数增长 | 取决于搜索策略 | 太慢了 |
 | 最佳 | O(n) | O(n) 用于存储输出 | 已接受 |

 ## 算法演练

 1.读取目标号码`n`。 该值本身告诉我们需要多少个术语，因为每个术语`1`准确贡献`1`到立方和。 
2. 创建一个包含以下内容的分解`n`整数的副本`1`。 得到的立方和是`n × 1³`，这正是`n`。 
3. 打印`n`作为术语数量，后跟术语列表。 最大可能的项数是`9241`，因此永远不会超过输出限制。 

为什么它有效：不变的是选择后`k`的副本`1`，部分立方和正好是`k`。 当算法完成选择后`n`份，总和正好是`n`。 每个选择的值都在允许的范围内，并且选择的值的数量是有效的，因为`n ≤ 9241 < 10000`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    print(n)
    print(" ".join(["1"] * n))

if __name__ == "__main__":
    solve()
```程序读取单个整数并将其直接用作项数。 列表构造准确地创建了`n`值的副本`1`。 

输出顺序很重要，因为第一行必须包含数字的计数。 之后，第二行包含实际的分解。 

不存在溢出问题，因为 Python 整数是任意精度的，并且最大输出仅包含`9241`小整数。 

## 工作示例

 考虑输入：```
3
```该算法创建三个副本`1`。 

| 步骤| n | 生成的条款 | 立方和|
 | ---| ---| ---| ---|
 | 开始| 3 | 空 | 0 |
 | 添加第一项 | 3 | 1 | 1 |
 | 添加第二项 | 3 | 1 1 | 1 2 |
 | 添加第三项 | 3 | 1 1 1 | 1 1 1 3 |

 最终总和是`1³ + 1³ + 1³ = 3`，与目标匹配。 

考虑输入：```
7
```| 步骤| n | 生成的条款 | 立方和|
 | ---| ---| ---| ---|
 | 开始| 7 | 空 | 0 |

 该示例表明该算法不需要搜索特殊的立方体恒等式。 它仅依赖于始终有效的身份`1³ = 1`。

 ## 边缘情况

 对于`n = 1`，该算法恰好创建了一项。 执行过程是：```
n = 1
answer = [1]
```立方和是`1³ = 1`，因此输出有效。 

为了`n = 9241`，算法创建`9241`条款。 执行过程是：```
n = 9241
number of terms = 9241
```立方和为：```
9241 × 1³ = 9241
```项数仍低于允许的最大项数`10000`，因此构造仍然有效。 

对于诸如以下的值`n = 3`，基于搜索的解决方案可能会尝试找到更短的表示形式，例如`1³ + 1³ + 1³`，但最优算法无需搜索即可做到这一点。 生成的序列始终具有所需的总和，因为每个单独的贡献都是可预测的。
