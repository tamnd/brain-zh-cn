 ## 解决方案
 ## 问题理解

 我们给定一个自然数`n`，但不是将其完美地输入计算器，而是每次按数字后都会意外地出现一个`+`按下按钮，a`-`按下按钮，或者什么也没有。 概率是固定的：`+`有概率发生`0.45`,`-`有概率发生`0.45`，并且没有额外的按钮发生的概率`0.10`。 

数字按正常顺序输入。 这些意外运算创建一个包含相同数字的算术表达式，可能被加号和减号分隔。 如果表达式以符号结尾，计算器将忽略最后一个符号。 任务是计算结果的期望值。 

输入的数字最多可以有`1000`数字，因此在具有固定大小整数类型的语言中不可能进行正常的整数算术。 更重要的是，任何试图枚举可能表达式的方法都是不可能的，因为每个数字后面都有三个选择，从而产生指数增长。 对数字进行线性扫描是预期的复杂性。 

棘手的部分是数字不是独立的。 如果数字后面没有出现运算符，则该数字可能会成为更大的多位数字的一部分。 例如，第一个数字`123`根据计算器是否创建贡献不同`1+23`,`12+3`， 或者`123`。 仅单独处理每个数字的解决方案将错过这些交互。 

考虑输入：```
12
```可能的表达式是`1+2`,`1-2`， 和`12`。 他们的期望值是：```
0.45 * 3 + 0.45 * (-1) + 0.10 * 12 = 2.1
```简单的逐位加法无法捕获串联情况。 

另一个边缘情况是单个数字：```
7
```后面没有数字，所以任何意外`+`或者`-`最后被忽略。 答案正是：```
7
```应用转换规则而不单独处理最后一位数字的解决方案可能会错误地修改该值。 

最后的边缘情况是一个很长的数字，例如：```
000000
```答案依然是`0`。 该算法必须适用于字符串，并且不能依赖于将输入转换为整数。 

## 方法

 暴力解决方案将通过尝试每个数字后的所有三种可能性来生成每种可能的表达式。 对于一个数字`n`数字，有`3^(n-1)`插入运算符的可能选择。 即使对于几十位数字，这也是不可行的，并且输入可以包含一千位数字。 

关键的观察结果是随机过程有少量需要记住的信息。 当查看数字的后缀时，两个值就足够了。 我们需要评估后缀的期望值，并且我们需要`10^(length of the first number in that suffix)`。 第二个值处理前一个数字连接后缀的情况，因为没有插入运算符。 

假设当前后缀以数字开头`d`其余后缀具有预期值`value`和预期的第一个数字长度因子`power`。 如果一个`+`或者`-`出现在之后`d`，第一个数字只是`d`。 如果什么也没有出现，`d`成为现有第一个数字的第一位数字，将其小数位值乘以十。 

从右到左的处理使这种关系变得简单。 第一个数字因子正好增长`9`添加数字时，可以仅使用两个存储的数量来更新预期值。 

蛮力方法之所以有效，是因为它直接对每个可能的计算器状态进行建模，但它会失败，因为状态数量呈指数增长。 所有后缀都可以通过两个期望来概括的观察结果将问题简化为一次通过。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(3^n) | O(3^n) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将数字作为字符串读取，因为它最多可能包含 1000 位数字。 
2. 从最后一位数字开始。 对于一位数后缀，预期值是数字本身。 该后缀中的第一个数字的长度为 1，因此小数因子为`10`。 
3. 从右向左移动剩余的数字。 对于当前数字`d`，保留已处理后缀的两个值：`value`是该后缀的预期结果。`power`是期望值`10`提升到该后缀的第一个操作数中的位数。 
4. 使用以下命令更新预期值：`new_value = 0.9 * d + 0.1 * d * power + 0.1 * value`第一项代表运算符出现在后面的情况`d`。 第二项代表串联。 第三项代表后缀的其余部分保持不变。 
5. 更新小数因子：`new_power = power + 9`当运算符出现在之后`d`，第一个操作数的长度为一。 当没有运算符出现时，第一个操作数将获得一个额外的数字。 期望简化为加九。 
6. 处理完每个数字后，打印最终的期望值。 

为什么它有效：

 不变的是，处理后缀后，`value`正是该后缀的预期计算器结果，并且`power`正是其第一个操作数的预期十进制乘数。 该转换考虑当前数字之后的所有三个可能事件并组合它们的概率。 由于转换保留了两种含义，因此处理整个字符串后的最终状态包含正确的期望值。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    s = input().strip()

    value = int(s[-1])
    power = 10.0

    for ch in reversed(s[:-1]):
        d = int(ch)
        value = 0.9 * d + 0.1 * d * power + 0.1 * value
        power += 9.0

    print("{:.12f}".format(value))

if __name__ == "__main__":
    solve()
```该代码将数字存储为字符串，以便安全地处理非常大的输入。 最后一个数字初始化后缀，因为它没有可以合并的后续数字。 

循环以相反的顺序处理所有剩余的数字。 变量`value`对应于处理后缀的预期结果，而`power`存储数字连接后缀开头时所需的预期小数位乘数。 

更新顺序很重要。 新的`value`必须使用旧的`power`和旧的`value`，因此分配是在增加之前执行的`power`。 

Python浮点数在这里有足够的精度，因为位数只有1000，所需的误差为`10^-6`。

 ## 边缘情况

 对于：```
7
```算法初始化`value`到`7`并且永远不会进入循环，因为没有剩余的数字。 答案依然存在`7`，这与忽略任何最终意外符号的事实相匹配。 

为了：```
12
```该算法以后缀开头`2`， 在哪里`value = 2`和`power = 10`。 处理数字`1`给出：```
0.9 * 1 + 0.1 * 1 * 10 + 0.1 * 2
= 2.1
```这结合了三种可能性：`1+2`,`1-2`， 和`12`。 

为了：```
000000
```每个数字都为零，因此两个更新项都保持为零。 该算法从不尝试将整个字符串转换为整数，从而避免溢出并保留前导零。 最终的答案是`0`。
