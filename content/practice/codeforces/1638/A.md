 ## 解决方案
 ## 问题理解

 我们给出了长度的排列$n$，这是一个包含所有整数的数组$1$到$n$正好一次。 我们可以精确地选择排列的一个连续子段并将其反转。 目标是使用这个单一反转产生字典顺序上最小的排列。 字典顺序意味着我们从左到右逐个元素地比较数组，它们不同的第一个位置决定哪个数组较小。 

例如，给定排列`[2,1,3]`, 倒车`[2,1]`产生`[1,2,3]`，比原来的小。 如果排列已经排序，则反转除单个元素之外的任何段都会使情况变得更糟，因此最佳操作是反转长度为 1 的段，从而有效地保持数组不变。 

约束表明$n$最多可以有 500 个，并且最多可以有 500 个测试用例。 这意味着一种朴素的暴力方法，尝试所有可能的部分，即$O(n^3)$如果我们逐个元素检查每个反转的效果，在最坏的情况下会太慢。 相反，我们需要一种策略来识别有效逆转的最佳细分。 

非明显的边缘情况包括已经排序的数组、第一个元素已经是 1 但其余元素未排序的数组，以及稍后可能出现多个最小元素的数组。 例如，`[1,4,2,3]`必须逆转`[4,2]`将 2 紧接在 1 之后，给出`[1,2,4,3]`。 粗心的方法可能会尝试始终从第一个元素开始反转，从而错过较小的可能性。 

## 方法

 暴力方法是尝试每对索引$(l, r)$，反转该段，并将所得排列与当前最佳排列进行比较。 这将涉及$O(n^2)$逆转，每次成本计算$O(n)$构造一个新数组，给出$O(n^3)$。 这适用于小$n$但对于$n = 500$和 500 个测试用例。 

关键的观察是，为了使排列按字典顺序变小，我们应该尝试尽早放置尽可能小的数字。 排列与恒等不同的第一个位置（排序排列）是我们应该采取行动的位置。 一旦我们找到第一个不是其位置最小的元素，我们就找到它后面的最小数字，并将段从第一个不正确的元素反转到该最小数字的位置。 这保证了字典顺序的尽早改进。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^3) | O(n^3) | O(n) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 从左到右迭代排列以找到第一个索引`i`在哪里`p[i]`不等于`i+1`。 这是当前排列开始与排序顺序不同的位置。 
2.如果没有这样的`i`存在，排列已经排序。 反转单元素段`[1,1]`满足“恰好一次反转”的要求。 
3.否则，找位置`j`后缀中最小元素的起始位置`i`。 这是我们想要提出的元素`i`。 
4. 反转子段`[i, j]`。 这会将最小的元素移动到最早的可能位置，并将较大的元素推到其后。 
5. 输出排列结果。 

工作原理：通过将当前不在位置的最小元素放置在排列偏离排序顺序的最早索引处，我们确保生成的排列在字典顺序上是最小的。 任何其他反转要么在第一个不同位置留下较大的元素，要么稍后移动最小的元素，从而产生更差的排列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        
        # find first index where permutation differs from sorted
        for i in range(n):
            if p[i] != i + 1:
                break
        else:
            # already sorted, reverse a single element
            print(*p)
            continue
        
        # find the smallest element in the suffix starting at i
        j = i + p[i:].index(min(p[i:]))
        
        # reverse the segment [i,j]
        p[i:j+1] = reversed(p[i:j+1])
        
        print(*p)

if __name__ == "__main__":
    solve()
```该解决方案首先读取测试用例的数量。 对于每个测试用例，它读取`n`和排列`p`。 然后，它识别出第一个不合适的元素，找到它之后的最小元素，反转段以将最小元素向前移动，并打印结果排列。 边缘情况（例如已排序的数组）由`else`条款关于`for`环形。 

## 工作示例

 **输入：**`[3, 2, 1, 4]`| 步骤| 我| j | 反转后的 p |
 | ---| ---| ---| ---|
 | 查找第一个不匹配 | 0 | - | - |
 | 后缀中最小的 | 2 | 2 | - |
 | 撤销`[0,2]`| 0 | 2 |`[1,2,3,4]`|

 这表明反转最小片段会产生最早可能的词典编排改进。 

**输入：**`[1, 4, 2, 3]`| 步骤| 我| j | 反转后的 p |
 | ---| ---| ---| ---|
 | 第一次不匹配 | 1 | - | - |
 | 后缀中最小的 | 2 | 2 | - |
 | 撤销`[1,2]`| 1 | 2 |`[1,2,4,3]`|

 该算法识别最早的错位元素 (4)，并通过反转向前移动其后的最小元素 (2)。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|

 ## 边缘情况

 对于长度为 1 的排列，例如`[1]`，该算法识别出没有元素不合适并简单地输出`[1]`。 对于已经排序的排列，例如`[1,2,3,4,5]`， 这`for`循环结束而不中断，并且`else`子句确保我们反转长度为 1 的段，保持排列不变。 对于最小数字位于中间的排列，例如`[1,3,4,2]`，算法正确识别第一个不匹配（`3`在索引 1) 处，查找后缀中的最小元素 (`2`在索引 3) 处，反转`[1,3]`，生产`[1,2,4,3]`。 这证实了该算法可以正确处理所有重要的边缘情况。
