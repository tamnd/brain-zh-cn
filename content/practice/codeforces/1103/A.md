 ## 解决方案
 ## 问题理解

 我们正在开发一块固定的 4 x 4 板，一开始是空的。 一串多米诺骨牌一一到来，每一张多米诺骨牌到来时都必须立即放置。 

每个多米诺骨牌要么是垂直的，覆盖同一列中的两个单元格，要么是水平的，覆盖同一行中的两个单元格。 一旦放置，棋盘可能会发生变化：如果任何行被完全填满，则整行会同时被擦除； 同样，如果任何列被完全填满，它也会被删除。 这些删除发生在每次放置之后，并且可能一次清除多行或多列。 

任务是决定将每个传入的多米诺骨牌放置在哪里，以便它始终适合当前的空闲单元，并且我们必须输出每个放置的位置。 输出位置是该多米诺骨牌接触的最小行和列，对应于垂直多米诺骨牌的左上角单元格或水平多米诺骨牌的最左边单元格。 

关键的限制是棋盘非常小，只有 16 个单元，而多米诺骨牌的数量可能高达 1000 个。这立即排除了任何试图随着时间的推移维持复杂的全局优化的策略。 即使是常数因子低效模拟也可以，只要每个步骤都受到 4 x 4 网格上的小型固定搜索的限制。 

一个微妙的困难来自于删除规则。 简单地“贪婪地填充单元格”而不模拟行和列清除的幼稚方法最终会失败，因为先前阻塞的空间在删除后可能会突然重新出现。 另一个失败的案例是假设固定的放置模式； 这些撤职使国家充满活力并依赖于过去的安置。 

最后一种边缘情况是多行或多列同时变满。 它们必须同时被清除，否则稍后的放置可能会错误地认为单元格仍然被占用。 

## 方法

 强力解释将尝试模拟每个多米诺骨牌在每一步的所有可能位置。 对于每个传入的块，我们将扫描所有有效位置并递归地尝试未来的放置。 这很快就会呈指数增长，因为即使在 4 x 4 板上，每个步骤也有多达数十种放置选择，并且可以有 1000 个步骤。 即使进行了修剪，分支因子也使这变得不可行。 

关键的观察结果是，董事会是如此之小，以至于我们永远不需要向前看。 相反，我们可以贪婪地进行模拟，同时始终保持有效的配置。 由于删除会不断重置电路板的某些部分，因此我们并不是构建最终的封装配置，而是在几乎全新的电路板上反复解决微小的封装问题。 

这允许一个建设性的策略：对于每个多米诺骨牌，我们只需搜索适合当前棋盘状态的第一个有效位置。 放置后，我们立即更新图板并清除任何完整的行或列。 由于网格的大小是恒定的，因此检查所有可能性会花费恒定的时间，并且完整的模拟与输入的长度呈线性关系。 

这样做的原因是任何本地有效的放置就足够了。 这些删除保证了董事会永远不会积累不可逆转的约束； 相反，它不断释放空间，防止死胡同。

 ## 算法演练

 我们维护一个 4 x 4 布尔网格来表示占用的单元格。 

1. 对于每个传入的多米诺骨牌，我们以固定顺序扫描网格以找到有效的位置。 

对于水平多米诺骨牌，我们寻找 r 行和 c 列，使得 (r, c) 和 (r, c+1) 都为空。 对于垂直多米诺骨牌，我们寻找 (r, c) 和 (r+1, c) 为空。

固定的扫描顺序确保了确定性并避免了歧义。 
2. 一旦找到有效的位置，我们将这两个单元标记为已占用，并将输出坐标记录为基于 1 的索引中的 (r, c)。 
3. 放置后，我们检查所有行。 如果一行的四个单元格都被占用，我们可以通过将它们设置为空来清除它。 
4. 然后我们检查所有列。 如果一列的四个单元格都被占用，我们会类似地清除它。 
5. 我们重复此清除步骤，直到没有行或列被完全填满，因为清除行可能会导致列变满，反之亦然。 

我们反复澄清的原因是，单个放置可能会引发级联删除。 

### 为什么它有效

 在每一步中，网格都准确地表示应用所有删除后的当前活动单元格集。 扫描总是能找到一个位置，因为板上最多有 16 个单元，并且删除可以防止永久饱和。 由于我们只将多米诺骨牌放置在两个空单元格中，因此我们永远不会违反重叠约束。 清除规则确保每当行或列满时，立即将其删除，恢复容量并防止死锁。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def clear(board):
    changed = True
    while changed:
        changed = False

        # check rows
        for r in range(4):
            if all(board[r][c] for c in range(4)):
                for c in range(4):
                    board[r][c] = 0
                changed = True

        # check cols
        for c in range(4):
            if all(board[r][c] for r in range(4)):
                for r in range(4):
                    board[r][c] = 0
                changed = True

def solve():
    s = input().strip()
    board = [[0] * 4 for _ in range(4)]
    out = []

    for ch in s:
        placed = False

        if ch == '1':  # horizontal
            for r in range(4):
                for c in range(3):
                    if board[r][c] == 0 and board[r][c + 1] == 0:
                        board[r][c] = board[r][c + 1] = 1
                        out.append((r + 1, c + 1))
                        placed = True
                        break
                if placed:
                    break

        else:  # vertical
            for r in range(3):
                for c in range(4):
                    if board[r][c] == 0 and board[r + 1][c] == 0:
                        board[r][c] = board[r + 1][c] = 1
                        out.append((r + 1, c + 1))
                        placed = True
                        break
                if placed:
                    break

        clear(board)

    print("\n".join(f"{r} {c}" for r, c in out))

if __name__ == "__main__":
    solve()
```该解决方案保留了 4 x 4 的占用网格，从而避免了任何复杂的数据结构。 放置逻辑是确定性扫描，始终选择第一个可用的拟合，这是安全的，因为网格很小并且我们从不需要最佳包装。 

清除功能是分开的，因为行和列的删除可以连锁，我们必须继续应用它们，直到达到稳定。 

一个常见的错误是忘记重复清除，如果新完成的行是在同一步骤中删除列后形成的，则可能会导致该行未被删除。

 ## 边缘情况

 一种微妙的情况是，随着时间的推移，由于多米诺骨牌放置模式的后半部分而不是单个明显的填充，导致一行变满。 该算法可以处理此问题，因为每次放置后都会应用清除，确保状态中不会保留陈旧的整行。 

另一种情况是行和列同时完成。 重复的清除循环确保即使其中一个间接触发另一个，两者也会被删除，从而防止中间状态不一致并保证板在下一次放置时保持有效。
