 ## 解决方案
 ## 问题理解

 城市是一个矩形网格。 每家酒店、每家餐厅都位于有坐标的十字路口$(x,y)$。 在相邻交叉路口之间移动需要花费一公里，因此两点之间的行进距离就是曼哈顿距离$$|x_1-x_2| + |y_1-y_2|.$$所有的朋友都从他们的酒店出发，前往同一家餐厅。 对于选择的餐厅，我们关心的成本不是所有朋友走过的总距离，而是单个朋友走过的最大距离。 

对于每家餐厅，我们必须计算$$\max_{\text{hotel } h} \left( |x_h-x_r|+|y_h-y_r| \right)$$并选择一家使该值最小化的餐厅。 我们必须输出最佳最大距离以及实现该距离的任何餐厅的指数。 

城市规模可以大到$10^9$，但这被证明是无关紧要的，因为我们永远不需要迭代网格单元。 重要的限制因素是酒店和餐馆的数量，最多可达$10^5$。 

需要将每家餐厅与每家酒店进行直接比较$$10^5 \times 10^5 = 10^{10}$$最坏情况下的距离计算，在 2 秒的限制内是完全不可能的。 我们需要一些接近线性或$O(n \log n)$。 

一些微妙的情况可能会导致错误的推理。 

考虑两家酒店：```
(1,100)
(100,1)
```和一家餐厅：```
(50,50)
```粗心的解决方案可能会尝试使用最大的酒店$x$或最大的$y$独立。 最远的酒店由曼哈顿度量确定，该度量结合了两个坐标。 只查看一个坐标就会丢失信息。 

另一个容易犯的错误是假设城市边界很重要。 例如：```
N = M = 10^9
hotel = (1,1)
restaurant = (10^9,10^9)
```距离简直就是$$(10^9-1)+(10^9-1),$$并且不需要遍历网格。 任何取决于城市区域的解决方案都会立即失败。 

第三个陷阱是处理重复的位置。 例子：```
Hotels:
(5,5)
(5,5)

Restaurants:
(5,5)
```答案是距离$0$。 该算法必须正常处理重复点，并且不能假设所有坐标都是不同的。 

## 方法

 蛮力方法很简单。 对于每家餐厅，计算其到每家酒店的曼哈顿距离并保留最大值。 在评估了所有酒店后，我们知道了该餐厅的最差距离。 对所有餐厅重复此操作即可得出最佳答案。 

这样做的原因很简单。 目标的定义正是酒店到餐厅的最大距离，因此明确检查每一对都会产生正确的结果。 

问题在于规模。 和$10^5$酒店和$10^5$餐厅，我们会评估$10^{10}$距离。 即使距离计算只需要几个机器指令，这也远远超出了极限。 

为了改善这一点，我们需要了解曼哈顿距离的结构。 

对于任何酒店$(a,b)$和餐厅$(x,y)$,$$|a-x|+|b-y|.$$曼哈顿几何的标准恒等式是$$|u|+|v| = \max \{ (u+v), (u-v), (-u+v), (-u-v) \}.$$替代$u=a-x$和$v=b-y$,$$|a-x|+|b-y| = \max \{ (a+b)-(x+y), (a-b)-(x-y), (-a+b)-(-x+y), (-a-b)-(-x-y) \}.$$对于固定餐厅，所有酒店的最大值变为$$\max \left( \max(a+b)-(x+y), \max(a-b)-(x-y), \max(-a+b)-(-x+y), \max(-a-b)-(-x-y) \right).$$关键的观察结果是，所有酒店信息都被压缩为四个全局最大值。 

让$$M_1=\max(a+b),$$

$$M_2=\max(a-b),$$

$$M_3=\max(-a+b),$$

$$M_4=\max(-a-b).$$一旦知道这四个值，就可以在恒定时间内计算出任何餐厅到酒店的最远距离。 

蛮力之所以有效，是因为它明确地搜索最远的酒店。 上面的观察用四个预先计算的极值替换了该搜索。 我们花费$O(C)$时间预处理酒店和$O(H)$评估餐厅的时间​​。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(CH)$|$O(1)$| 太慢了 |
 | 最佳|$O(C+H)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 读取所有酒店坐标。 
2. 计算所有酒店的四个值：$$M_1=\max(x+y)$$

$$M_2=\max(x-y)$$

$$M_3=\max(-x+y)$$

$$M_4=\max(-x-y)$$这些是稍后需要的唯一酒店统计数据。 
3、对餐厅进行一一处理。 
4. 对于餐厅$(x,y)$, 计算$$d= \max( M_1-(x+y), M_2-(x-y), M_3-(-x+y), M_4-(-x-y) ).$$该值等于从餐厅到任何酒店的最大曼哈顿距离。 
5. 保留值最小的餐厅$d$。 
6.输出最佳距离以及对应的从1开始的餐厅索引。 

### 为什么它有效

 对于每个酒店，曼哈顿距离可以重写为四个线性表达式中的最大值。 当我们取所有酒店的最大值时，每个线性表达式都取决于酒店在该方向上获得的最大值。 这些最大值正是$M_1,M_2,M_3,M_4$。 

对于固定餐厅，使用这些预先计算的最大值评估四个表达式会得到与单独检查每个酒店相同的结果。 由于计算出的值恰好是最远的酒店距离，因此比较各个餐厅的这些值会选择最小化最差旅行距离的餐厅。 不涉及近似，因此算法是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    c = int(input())

    INF = 10**30

    m1 = -INF
    m2 = -INF
    m3 = -INF
    m4 = -INF

    for _ in range(c):
        x, y = map(int, input().split())

        m1 = max(m1, x + y)
        m2 = max(m2, x - y)
        m3 = max(m3, -x + y)
        m4 = max(m4, -x - y)

    h = int(input())

    best_dist = INF
    best_idx = 1

    for idx in range(1, h + 1):
        x, y = map(int, input().split())

        dist = max(
            m1 - (x + y),
            m2 - (x - y),
            m3 - (-x + y),
            m4 - (-x - y)
        )

        if dist < best_dist:
            best_dist = dist
            best_idx = idx

    print(best_dist)
    print(best_idx)

solve()
```代码的第一部分计算所有酒店的四个极端变换坐标。 这对应于将所有酒店信息压缩为四个数字的预处理步骤。 

餐厅循环使用这四个最大值来评估恒定时间内最远的酒店距离。 由于输出中需要餐厅索引，因此循环使用从 1 开始的索引运行。 

所有算术都很容易适合 64 位整数。 坐标最多为$10^9$，因此变换后的值大致受$2 \cdot 10^9$。 Python 整数会自动处理这个问题。 

一个常见的实施错误是忘记餐厅答案是四个转换表达式中的最大值，而不是最小值。 每个表达式代表曼哈顿距离恒等式中的一种可能的符号配置。

 ## 边缘情况

 考虑重复的位置：```

2
5 5
5 5
1

```最大值变为：$$M_1=10,\quad M_2=0,\quad M_3=0,\quad M_4=-10.$$对于餐厅$(5,5)$,$$\max(0,0,0,0)=0.$$算法输出距离$0$，与真实答案完全匹配。
