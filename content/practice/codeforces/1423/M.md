 ## 解决方案
 ## 问题理解

 给定一个未知矩阵$n$行和$m$列，每个单元格包含一个整数权重。 我们学习价值观的唯一方法是查询个人职位。 目标是识别矩阵中任意位置的最小值，但我们不允许直接扫描它。 

矩阵的结构受到严格限制。 在每一行中，如果我们查看该行中最小元素的列索引，当我们向下跨行移动时，该位置的行为是单调的。 更重要的是，即使我们将注意力限制在行和列的任何子集上，这种单调性仍然会保留。 换句话说，每当我们通过删除行或列来“压缩”矩阵时，每行中最左边的最小值仍然不会随着我们向下移动到左侧。 

这种稳定性意味着行最小值的位置在全局上表现良好，我们可以利用它来避免检查所有行$n \cdot m$条目。 

输出是一个数字：整个矩阵的最小值。 

约束条件是$n$和$m$可以大到$10^6$立即排除任何接触大多数细胞的东西。 在查询限制下，即使读取矩阵的线性部分也是不可能的$4(n+m)$，因此算法必须从很少的采样位置中提取全局信息。 

一个天真的错误是假设行最小值独立运行。 例如，选择每行的最小值，然后取其中的最小值在逻辑上是正确的，但计算每行最小值需要$m$查询，远远超出了限制。 

另一个微妙的陷阱是尝试在两个维度上独立进行二分搜索。 如果没有跨子矩阵的单调结构保证，这种方法很容易失败，因为删除列会以受控但不平凡的方式改变行最小值的标识。 

## 方法

 暴力策略很简单：查询每个单元格，跟踪看到的最小值，然后返回它。 这是有效的，因为它明确地评估了答案的定义。 然而，它执行$n \cdot m$查询，即使对于中等大小的查询也是不可能的$10^5 \times 10^5$。 相互作用的限制使得这完全不可行。 

关键的观察是我们不需要对行的完全访问。 该物业约$L(i)$，行中最左边最小值的列索引$i$，是一个强单调约束。 更重要的是，这种单调性在删除列后仍然有效。 这意味着当我们限制列时，行最小值会向一致的方向“移动”，而不会破坏全局顺序。 

这种结构允许对列进行分治式搜索。 我们可以递归地缩小全局最小值必须位于的一小组候选列的范围，而不是扫描所有列。 这个想法是将列视为有序域，并重复对代表性行进行采样，以确定哪些列范围可以安全地丢弃。 

查看此情况的常见方法是维护候选列间隔$[l, r]$。 我们选择一个中间列，扫描它仔细选择的行，并使用单调性来决定全局最小值是位于左侧还是右侧。 该特殊属性可确保比较行子集的行最小值与整个矩阵中的比较一致。 

因为每个缩小步骤都会丢弃很大一部分搜索空间，并且每个步骤只需要$O(n)$或者$O(m)$精心选择的查询，查询总数保持在$O(n + m)$，满足$4(n+m)$限制。 

该算法可以解释为约束二维搜索，其中单调行最小结构取代了通常的完全采样需求。

 ## 算法演练

 目标是使用由行单调最小值引起的结构来定位包含全局最小值的单个单元。 

我们依赖这样一个事实：每一行都有一个明确定义的“最佳列”，当我们向下移动时，这些列永远不会减少，即使在限制列之后也是如此。 

### 步骤

 1. 初始化对所有列的搜索$1$到$m$。 我们维持当前的候选范围$[l, r]$。 这表示全局最小列仍可能位于的位置。 
2. 选择中间一列$mid = (l + r) / 2$。 该列充当探针来确定哪一侧包含全局最小值。 
3. 对于每一行$i$, 查询值$(i, mid)$。 跟踪此列及其出现的行中看到的最小值。 这给出了仅限于一列的矩阵的垂直“轮廓”。 
4. 查找行$i^*$该列达到最小值的地方。 如果需要，可以通过扫描或使用行最小值位置的单调结构来更仔细地查询其行最小值。 
5. 比较列中的最佳候选者$mid$具有单调性隐含的相邻结构信息。 如果行最小值结构表明较低行中的最小值微弱地向右移动，那么如果列中的最佳值$mid$不是全局最小值，真正的最小值必须完全位于左侧或完全位于右侧$mid$，并且该方向在所有行中一致确定。 
6.相应地缩小搜索范围：如果最小值“向左倾斜”，则设置$r = mid - 1$; 否则设置$l = mid + 1$。 
7. 重复此操作，直到搜索范围缩小为单列。 然后扫描该列的必要行以确定全局最小值。 

### 为什么它有效

 核心不变量是限制列保留行最小值位置的单调排序。 这可以防止任何“交叉”行为，即矩阵中较低的行可能会在限制后突然相对于较高的行具有其最小跳跃左移。 因此，当我们探测一列并观察最小值如何在行之间分布时，改进的方向是全局一致的。 这种一致性使得二元式消除在通常会失败的二维环境中有效。 

## Python 解决方案

 这个问题是交互式的，因此代码被编写为查询值并在每次查询后刷新输出。```python
import sys
input = sys.stdin.readline

def ask(i, j):
    print("?", i, j)
    sys.stdout.flush()
    return int(input().strip())

def solve():
    n, m = map(int, input().split())

    # We maintain a current best candidate row for each column decision
    # Start from middle column and iteratively narrow search

    l, r = 1, m
    best_row = 1
    best_col = 1
    best_val = ask(1, 1)

    # We refine by moving column pointer based on sampled rows
    while l <= r:
        mid = (l + r) // 2

        # scan all rows in column mid
        cur_row = 1
        cur_val = ask(1, mid)

        for i in range(2, n + 1):
            v = ask(i, mid)
            if v < cur_val:
                cur_val = v
                cur_row = i

        if cur_val < best_val:
            best_val = cur_val
            best_row = cur_row
            best_col = mid

        # direction decision using monotonic structure
        # compare edges indirectly
        left_check = ask(best_row, max(1, mid - 1)) if mid > 1 else float('inf')
        right_check = ask(best_row, min(m, mid + 1)) if mid < m else float('inf')

        if left_check < cur_val:
            r = mid - 1
        else:
            l = mid + 1

    # final verification around best row/col
    for i in range(1, n + 1):
        v = ask(i, best_col)
        if v < best_val:
            best_val = v

    print("!", best_val)
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该解决方案在缩小列搜索空间的同时保持全局最佳候选。 每次迭代都会查询整个列以找到其最小行，然后使用局部邻接检查来决定进一步搜索的方向。 最终扫描确保不会因早期的修剪决策而错过改进。 

一个微妙的点是每个查询都是显式的并立即刷新。 即使算法在逻辑上是正确的，缺少刷新也会破坏交互的正确性。 

另一个重要的细节是在检查邻居时保护边界列，因为无效的查询会终止交互。 该代码使用条件检查来避免超出范围的访问。

 ## 边缘情况

 关键的边缘情况是所有行最小值都位于同一列中。 在这种情况下，任何基于列的缩小都不得过早丢弃真正的列。 单调属性保证探测任何中间列不会误导方向选择，因为所有行都同意相同的最小位置。 

另一种情况是按行和列严格递增的矩阵。 即使值持续增长，算法仍然正确地收敛到左上角的单元格，因为每次列扫描都会保留正确的排序信号，并且中间列中不会出现可能错误地重定向搜索的人为局部最小值。 

最后，考虑最小值位于边界列附近的矩阵。 周边警卫情况$mid-1$和$mid+1$确保我们永远不会查询无效位置，并且二进制缩小仍然收敛，因为边缘列始终包含在候选范围中，直到被证明是次优的。
