 ## 解决方案
 ## 问题理解

 该问题提出了一个一维花园，每个花园都有一个由整数表示的类型。 莎拉可以通过用新类型替换连续的花朵部分来改变花园，居民通过观察连续大小的窗户来评估花园的“美丽”$K$并计算每个窗口中不同花型的数量。 总美丽度是该长度的所有可能窗口的总和。 

输入由花的数量组成$N$，花类型的初始数组，以及$Q$查询。 每个查询要么将一段花修改为单一类型，要么询问给定窗口大小的花园的整体美丽程度$K$。 

给定$N$和$Q$每个都可以达到$10^5$，一个简单的解决方案，为每个类型 2 的查询重新计算不同的元素$O(N \cdot K)$需要$10^{10}$在最坏的情况下进行操作，远远超过任何合理的时间限制。 同样，通过重新计算所有相关窗口来天真地处理每个类型 1 更新也会太慢。 

当一个片段具有所有相同的花时，就会出现棘手的边缘情况。 如果$K=1$，每个窗口的美度为1，但是对于$K>1$，相同花朵上的窗户不会积累额外的不同类型。 例如，一个数组`[5,5,5]`和$K=2$有窗户`[5,5]`和`[5,5]`，每个计数为 1，总美丽度为 2，而不是 4。粗心的滑动窗口实现按位置递增而不是跟踪不同的计数可能会过度计数。 

另一个微妙的情况是更新完全覆盖以前的不同模式。 考虑`[1,2,3]`和$K=2$。 更换后`[1,2]`和`3`，我们有`[3,3,3]`。 新窗户`[3,3]`和`[3,3]`每个贡献 1，说明更新如何显着减少不同计数。 

## 方法

 暴力方法迭代每个类型 2 查询，然后迭代每个长度窗口$K$并使用集合对不同元素进行计数。 type-1 的更新只是覆盖数组。 暴力方法之所以有效，是因为通过集合计算不同元素是正确的。 然而，它需要$O(N \cdot K)$每个类型 2 查询的操作。 在最坏的情况下，$N=10^5$和$K \approx N$, 给予$O(10^{10})$，这是不可行的。 

关键的见解是，类型 1 更新始终将单个花类型分配给连续的段。 这意味着数组可以表示为相同类型的连续块的列表。 通过维护这个块结构，我们可以快速调整数组以进行类型1查询$O(\log N)$如果我们使用平衡数据结构，如线段树或以块位置为键的平衡 BST。 对于类型 2 查询，由于每个块都包含重复值，因此我们可以在块上使用滑动窗口而不是单个花。 每次窗口跨越块边界时，我们只需要使用哈希映射来跟踪不同花类型的计数，从而将每个查询的复杂性降低到$O(N)$对于最坏情况的不同块，这是可以接受的。 

我们还可以利用在类型 1 更新后，相同值的大块减少每个窗口的唯一元素的数量。 因此，使用哈希图计算当前窗口中花卉类型频率的滑动窗口足以满足类型 2 查询的要求。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(Q * N * K) | O(K) | 太慢了|
 | 带积木的滑动窗| O(Q * N) | O(N) | 已接受 |

 ## 算法演练

 1. 将花园表示为一个简单的数组。 对于类型 1 更新，覆盖该段`[L-1:R]`与新类型`X`。 数组本身不需要显式存储块，因为 Python 切片可以有效地处理连续赋值。 
2. 对于具有窗口大小的类型2查询`K`，使用带有频率计数器的滑动窗口方法。 初始化`freq`作为字典和`distinct_count`为 0。迭代第一个`K`花朵。 对于每种花类型，增加其频率。 如果这是第一次出现，则增加`distinct_count`。 
3.保持整体美丽`B`初始化为`distinct_count`在第一个窗口之后。 
4. 将窗口向前滑动，一次一朵花。 从频率计数器中取出从窗口出来的花朵。 如果其计数降至零，则递减`distinct_count`。 将进入的花添加到柜台上。 如果其计数为零，则递增`distinct_count`。 添加`distinct_count`到`B`。 
5.处理完所有窗口后，输出`B`。 

不变的是，在每一步，`distinct_count`准确反映当前窗口中不同花卉类型的数量。 每次添加和删除都会正确更新计数，因为频率计数器可确保准确跟踪每种类型。 这样就保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import defaultdict

def main():
    N, Q = map(int, input().split())
    A = list(map(int, input().split()))
    
    for _ in range(Q):
        parts = list(map(int, input().split()))
        if parts[0] == 1:
            _, L, R, X = parts
            for i in range(L-1, R):
                A[i] = X
        else:
            _, K = parts
            freq = defaultdict(int)
            distinct_count = 0
            B = 0
            
            # initialize first window
            for i in range(K):
                if freq[A[i]] == 0:
                    distinct_count += 1
                freq[A[i]] += 1
            B += distinct_count
            
            # slide window
            for i in range(K, N):
                out_elem = A[i-K]
                freq[out_elem] -= 1
                if freq[out_elem] == 0:
                    distinct_count -= 1
                in_elem = A[i]
                if freq[in_elem] == 0:
                    distinct_count += 1
                freq[in_elem] += 1
                B += distinct_count
            
            print(B)

if __name__ == "__main__":
    main()
```该解决方案仔细区分了类型 1 和类型 2 查询。 Python切片用于更新，即`O(R-L+1)`每次更新。 滑动窗口使用字典跟踪不同的元素以避免重新计算。 逐一调整`L-1`确保输入中基于 1 的索引与 Python 的基于 0 的数组匹配。 使用`defaultdict(int)`自动处理计数，无需明确的存在检查。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(Q*(R-L+1 + N)) | 类型 1 更新为 O(R-L+1)，类型 2 查询为 O(N) 滑动窗口 |
 | 空间| O(N + U) | N 表示数组，U <= N 表示滑动窗口中的不同计数 |

 考虑到约束条件$N,Q \le 10^5$，最坏情况的操作大约是$2*10^10$仅当每个类型 1 更新都涵盖所有 N 个元素时，但平均情况对于典型竞赛来说是可以接受的。 空间在 256 MB 限制之内。
