 ## 解决方案
 ## 问题理解

 问题在于烤面包时利润最大化。 可用的面团数量是固定的。 面包可以不加馅料，也可以加几种馅料之一。 每个包子都会消耗一些面团和一定量的某种特定的馅料，然后给出一定数量的钱。 不包馅的包子只消耗面团，有自己固定的成本和回报。 目标是选择每种类型要烘烤多少个面包，以使总收入尽可能大。 

输入给出了可用的面团、馅料类型的数量以及每种面包类型的要求和奖励。 对于每种馅料类型，我们知道有多少馅料，一个包子消耗多少馅料，需要多少面团，以及它能赚多少钱。 产出是使用任意包子组合后可能获得的最大收入。 

面团数量最多1000个，馅料种类最多10种。 小面团极限是主要线索。 取决于面团数量的解决方案可以提供动态编程状态。 尝试每种类型的所有可能数量的面包的解决方案将随着馅料类型的数量呈指数增长，因此它是不合适的。 

一个常见的错误是单独处理每种馅料并分别最大化每种馅料的选择。 这会失败，因为所有面包类型共享相同的面团资源。 例如：```
Input:
10 1 10 100
5 5 4 100

Output:
200
```最好的选择是烤两个包子，用8个面团和10个馅。 仅基于馅利润密度的贪婪选择可能会错误地为不包馅的面包保留面团或选择更少的馅面包。 

另一种极端情况是馅料甚至无法制作一个完整的面包。 例如：```
Input:
5 1 1 1
3 4 10 100

Output:
5
```馅料有，但没有足够的面团来做包子。 唯一可能的行动是做五个素面包。 仅检查馅料可用性而忽略面团要求的解决方案将产生错误的答案。 

最后的边界情况是剩余资源无法使用时。 例如：```
Input:
7 1 3 5
4 4 2 10

Output:
15
```两个包子要用4个面团和8个馅，但实际上只能做一个包子，因为馅量有限。 剩余的资源无法转换成另一个部分包子。 

## 方法

 直接的方法是尝试每种馅料类型的所有可能数量的面包。 对于每种馅料类型，我们可以选择从零个面包到可用馅料允许的最大数量的任何地方。 选完所有的包子后，我们将剩下的面团填入素包子里。 这是正确的，因为每个有效的烘焙计划都对应于枚举所考虑的某种组合。 

问题在于组合的数量。 一个馅料数量最多可以有100种选择，馅料类型可以有10种。 在最坏的情况下，探索所有可能性意味着周围$100^{10}$组合，这远远超出了任何比赛时间限制所能处理的。 

关键的观察结果是，面团是每种面包类型共享的唯一资源。 馅料资源是针对自己的包子类型的本地资源，而面团数量只有 1000 个。我们不必单独跟踪每个馅料决策，而是可以逐一处理馅料类型，并为已花费的每种可能的面团量保持最佳利润。 

对于一种馅料类型，我们有有限数量的相同选择：烘烤零个面包、一个面包、两个面包，依此类推，直到馅料或面团用完。 这是有界背包过渡。 处理完所有的包子后，剩下的面团总能转化为原味包子，所以最终的答案是通过检查每一个可能用于包子的面团量来得到的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(100^m) | O(100^m) | O(1) | O(1) | 太慢了|
 | 最佳| O(m * n * 100) | O(n) | 已接受 |

 ## 算法演练

 1. 创建一个动态规划数组，其中`dp[x]`代表正确使用后可获得的最大金钱`x`到目前为止加工过的包子面团的克数。 最初，只能使用零面团，所以`dp[0] = 0`而其他所有状态都是不可能的。 
2. 独立加工每种馅料。 对于当前的馅料，计算最多可以做多少个包子。 这个限制来自于可用的馅料量和可用的面团。 
3.用这种馅料做的包子，尽可能多地尝试一下。 如果我们做`k`面包，他们吃`k * c`面团并给予`k * d`钱。 通过添加此选择，从前一个状态更新下一个动态编程状态。 
4. 完成此填充类型后，用新计算的状态替换旧状态。 这可以防止使用相同的填充物的次数超过其存在的次数。 
5、所有的馅料都处理完后，考虑包子的面团用量。 如果`x`面团已用完，剩下的`n - x`面团可以创造`(n - x) / c0`普通的包子，带来额外的利润`((n - x) / c0) * d0`。 
6. 取所有可能的最大值`x`。 这涵盖了夹馅面包和原味面包的所有有效组合。 

不变的是，在处理某些馅料类型后，`dp[x]`包含在所有正确使用的选择中可能获得的最佳收入`x`面团上那些加工过的馅料类型。 下一个馅料的每种可能选择要么使用零个面包，要么使用一些有效数量的面包，因此转换会考虑不变量可以继续保持的每种方式。 在最终的馅料类型之后，为每个剩余的面团量添加尽可能最佳的原味面包用量，即可给出最佳的完整烘焙计划。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, c0, d0 = map(int, input().split())

    stuffings = []
    for _ in range(m):
        a, b, c, d = map(int, input().split())
        stuffings.append((a, b, c, d))

    neg = -10**18
    dp = [neg] * (n + 1)
    dp[0] = 0

    for a, b, c, d in stuffings:
        ndp = [neg] * (n + 1)

        limit = a // b
        for used in range(n + 1):
            if dp[used] == neg:
                continue

            for cnt in range(limit + 1):
                dough = used + cnt * c
                if dough > n:
                    break
                ndp[dough] = max(ndp[dough], dp[used] + cnt * d)

        dp = ndp

    ans = 0
    for used in range(n + 1):
        if dp[used] == neg:
            continue
        plain = (n - used) // c0
        ans = max(ans, dp[used] + plain * d0)

    print(ans)

if __name__ == "__main__":
    solve()
```输入解析将每个填充类型存储为一个元组，因为每种类型在动态编程转换期间都是单独处理的。 

数组`dp`对无法到达的状态使用不可能的值。 这可以避免意外使用无法创建的状态。 价值`-10**18`安全地低于任何可能的答案，因此它在 Python 中充当负无穷大而无需担心溢出问题。 

对于每种填充类型，都会创建一个新数组。 这是防止重复服用超出其可用量的相同馅料的部分。 内部循环尝试当前馅料中所有可能的面包数量，以及边界`dough > n`一旦超过面团限制，就停止不必要的工作。 

最后的循环与馅料的过渡是分开的，因为普通的面包有无限的可用性。 一旦知道了花在包子上的面团量，最好的原味包子选择就确定了。 整数除法可以正确处理剩余的面团，因为无法制作不完整的面包。

```每种馅料加工后的重要状态是：

 | 步骤| 使用的面团| 最佳利润|
 | --- | --- | --- |
 | 初始| 0 | 0 |
 | 馅后1| 4 | 200 | 200

 最好的包子州用了10个面团，赚了241。普通包子没有面团了，所以最终答案是241。 

该轨迹显示了DP为什么保留不同的面团数量而不是只保留最高的利润。 一个短期利润较少的国家可以为未来更好的选择留出空间。

 ## 边缘情况

 对于有馅但无法制作包子的情况：```
5 1 1 1
3 4 10 100
```DP看到馅料类型只能做零个包子，因为每个包子需要10个面团，而只有5个。 唯一可到达的状态是`dp[0] = 0`。 最后一步添加五个普通面包，得到 5 个。 

对于贪婪利润选择失败的情况：```
10 1 10 100
5 5 4 100
```该算法不会在本地做出决定。 它保留了两种可能性：把面团花在包子上，把面团留起来做普通包子。 它评估了最终的组合，发现两个包子的得分为 200，这比一个普通的包子要好。 

对于有剩余资源的情况：```
7 1 3 5
4 4 2 10
```馅料转换创建了制作零个或一个馅包子的状态。 两个包子是不可能的，因为只有四个包子。 拥有一个包子的州使用两个面团，收入为 10。还剩下五个面团，这样就可以为另外 5 个面团制作一个普通包子，最终答案为 15。
