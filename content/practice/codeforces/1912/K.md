 ## 解决方案
 ## 问题理解

 给定一个整数序列，我们需要计算它的子序列中有多少满足特定的结构约束。 通过按升序选择一些索引来形成子序列，保持值的原始顺序但可能跳过元素。 

该约束应用于局部：如果我们采用任何有效的子序列，则该子序列内的每组三个连续元素必须具有偶数和。 由于奇偶性是影响偶数的唯一因素，因此该条件仅取决于元素是偶数还是奇数。 

当三个数中奇数元素的个数为零或两个时，三个数的和恰好为偶数。 这已经意味着强大的结构限制：奇数和偶数元素不能任意出现，并且子序列的奇偶校验模式受到高度约束。 

任务是计算满足此条件的所有长度至少为 3 的子序列，以 998244353 为模。 

约束很大，n 高达 2 × 10^5，这排除了任何显式枚举子序列的方法。 即使 O(n^2) 也是临界值，因此解必须接近线性或具有小常数的线性对数。 任何显式跟踪子序列的解决方案都会失败，因为子序列的数量是指数级的。 

一个微妙的边缘情况是当序列已经很小但奇偶校验结构强制许多有效的子序列时。 例如，如果所有元素都是偶数，则每个子序列都满足条件，因为每个三元组和都是偶数。 幼稚的方法可能仍然尝试显式地验证每个子序列的三元组，从而导致不必要的工作。 另一个边缘情况是交替奇偶校验序列，其中局部约束变得严格，只有非常特定的模式才能生存。 

## 方法

 暴力方法试图枚举每个子序列并检查有效性。 对于每个子序列，我们扫描其三元组并验证奇偶校验条件。 这是正确的，因为它直接遵循定义。 然而，子序列的数量是 2^n，即使 n = 40 这也已经不可行，因此这种方法立即失败。 

关键的简化来自于将条件转化为奇偶动力学。 让我们将每个元素编码为 0（偶数）和 1（奇数）。 条件表示对于每个连续的三元组 (x, y, z)，我们必须有 x + y + z == 0 (mod 2)。 这相当于二进制形式的 x ⊕ y ⊕ z = 0，即 z = x ⊕ y。 

这意味着一旦我们选择了子序列的前两个奇偶校验，接下来的每个奇偶校验都是唯一确定的。 整个子序列由 GF(2) 上的递归关系控制。 因此，有效子序列与通过选择起始对然后贪婪地扩展而生成的序列完全对应，同时确保我们可以使用原始数组中的元素实现所需的奇偶校验模式。 

这将问题从“选择任何子序列”转变为“计算与某些奇偶校验确定的自动机转换相匹配的子序列”。 我们可以从左到右处理数组，并动态计算可以形成以给定状态结束的部分有效序列的方式的数量。 由于下一个元素是由前两个元素确定的，因此状态空间的大小是恒定的（最后两个奇偶校验有四种可能性），并且转换仅取决于当前元素是否可以扩展状态。 

我们还需要强制长度至少为三，因此我们仅在第三个元素形成后才计算贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 奇偶校验状态下的最佳 DP | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将每个元素压缩为其奇偶校验：0 表示偶数，1 表示奇数。

我们维护一个 DP 表，其中 dp[a][b] 表示以一对奇偶校验 (a, b) 结尾的子序列的数量，并且根据三元组规则已经有效。 我们还为长度至少为 3 的有效子序列维护一个答案累加器。 

1. 将数组转换为奇偶校验数组p。 

这消除了所有不相关的幅度信息，因为在每个约束中只有均匀性才重要。 
2. 将 dp 初始化为一个用零填充的 2 × 2 表。 

每个状态代表部分子序列中最后两个选择的元素。 
3. 迭代数组中的元素。 

对于每个奇偶校验 x = p[i]，我们考虑它如何扩展现有状态并启动新状态。 
4. 首先，将 x 视为子序列的潜在第二个元素。 

任何先前的单元素选择（隐式跟踪）都可以与 x 配对以形成 dp[*][x] 状态。 
5. 然后，对于每个现有状态 (a, b)，我们检查是否可以附加 x。 

有效的条件是 (a + b + x) 是偶数，相当于 (a ⊕ b ⊕ x = 0)。 如果这个成立，我们可以将 dp[a][b] 扩展到 dp[b][x]。 
6. 每当我们扩展一个已经代表至少两个转换的状态时，我们也将其视为有效的子序列贡献。 
7. 更新新表中的 dp 以避免覆盖同一迭代内的转换。 
8. 将过渡期间收集的所有贡献相加作为最终答案。 

关键的不变量是 dp[a][b] 始终计算满足每个内部位置的所有三重约束的奇偶校验 a、b 结尾的子序列的数量。 由于每个扩展都在本地强制执行三重奇偶校验条件，因此任何构造的序列在全局范围内仍然有效。 相反，任何有效的子序列都必须恰好对应于通过这些状态的一条路径，因为最后两个奇偶校验唯一地确定是否允许扩展。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    p = [x & 1 for x in a]
    
    dp = [[0, 0], [0, 0]]
    ans = 0
    
    for x in p:
        ndp = [[0, 0], [0, 0]]
        
        # start new pairs (implicitly from single elements)
        # treat x as second element after any previous single element
        for b in [0, 1]:
            ndp[b][x] = (ndp[b][x] + 1) % MOD
        
        # extend existing sequences
        for a0 in [0, 1]:
            for b0 in [0, 1]:
                cnt = dp[a0][b0]
                if cnt == 0:
                    continue
                if (a0 ^ b0 ^ x) == 0:
                    # valid triple, extend
                    ndp[b0][x] = (ndp[b0][x] + cnt) % MOD
                    # sequences of length >=3 contribute here
                    ans = (ans + cnt) % MOD
        
        dp = ndp
    
    print(ans % MOD)

if __name__ == "__main__":
    solve()
```该代码将值压缩为奇偶校验，并在最后两个选定的奇偶校验上运行 DP。 转换规则对每个三元组强制执行 XOR 条件。 dp 表仅存储对状态，这已经足够了，因为下一个有效性仅取决于最后两个元素。 

初始化步骤将每个元素视为从假设的单元素开始的可能扩展。 这是避免显式维护长度为 1 的状态的标准技巧。 

仅当有效扩展产生长度至少为 3 的序列时，ans 变量才会累积贡献，这与使用 dp 转换时完全对应。 

必须小心每次迭代使用新的 ndp 数组，因为就地更新会错误地允许多次使用同一元素。

    input = sys.stdin.readline

 ## 边缘情况

 当所有数字都是偶数时，每个三元组都是有效的，因为每个和都是偶数。 该算法通过允许所有 dp 转换而不受限制地处理此问题，从而通过重复状态扩展来正确计数长度至少为 3 的所有子序列。 

当所有数字都是奇数时，每个三元组和也是奇数 + 奇数 + 奇数 = 奇数，因此没有一个三元组是有效的。 在这种情况下，条件 (a ⊕ b ⊕ c = 0) 对于每个三元组都失败，并且 dp 永远不会累积超过长度 2 的贡献，从而导致有效子序列为零。 

当序列交替奇偶校验时，有效扩展变得高度受限，因为异或条件很少适用于任意三元组。 DP 确保只有一致的奇偶校验链才能生存，并且所有无效转换都会被自然过滤掉，因为它们不满足 XOR 约束。
