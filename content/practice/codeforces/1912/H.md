 ## 解决方案
 ## 问题理解

 我们可以将系统视为一个有向完整图$n$每个有序的不同城市对都有可能有直飞航班的城市，但每个航班每天只能使用一次。 每个乘客都提出一个要求，即必须使用一系列定向航班将他们从源城市路由到目的地城市，并且同一航班不能在所有乘客中重复使用。 

任务不是为乘客找到最短路径。 相反，我们必须安排一组有向边，每个有向边最多使用一次，以便对于每个乘客来说，都存在沿着所选边从起点到终点的有向路径。 在所有此类调度中，我们希望使用的边数最少，或者确定不存在调度。 

关键的隐藏解释是，我们正在构建一个有向多级路由网络，该网络使用尽可能少的有向边同时嵌入所有所需的源到目标可达性。 

约束在特定方面是严格的。 城市数量最多 1000 个，但乘客数量最多可达 100000 人，这意味着我们无法承受任何二次方的费用。$m$。 然而，由于所有移动都发生在完整的有向图上，因此可行性结构仅取决于源和目的地如何交互，而不取决于端点之外的单个乘客的身份。 

一个幼稚的心理模型是尝试独立地为每个乘客构建明确的路径，然后合并所有边。 这会立即失败，因为不同的乘客会大量重复边缘，而我们无法控制极少性。 

第二种常见的故障模式是假设由于每条边都存在，我们总是可以连接每条边$a_i \to b_i$直接并完成。 这忽略了每条边的一次性限制； 不允许多名乘客使用同一条直接边缘。 

另一个微妙的边缘情况是当所有乘客形成循环依赖时，例如$1 \to 2$,$2 \to 3$,$3 \to 1$。 仅独立地将源连接到接收器的贪婪方法可能会低估满足多种需求的中间路由边缘的需求。 

## 方法

 暴力尝试会尝试为每个乘客分别分配一条路径，可能是通过贪婪地选择中间城市或根据请求运行最短路径构建。 由于图是完整的，因此每条路径的长度最多为 1，但会出现冲突，因为每个有向边只能全局使用一次。 这将问题转化为选择一个最小尺寸的有向边集，其传递闭包包含所有所需的对。 在最坏的情况下，检查所选边集的可行性需要重新计算可达性，这可能会花费$O(n(n+m))$每次尝试或更糟，并且边缘子集的数量是指数级的。 这远远超出了可行的限度。 

关键的见解是停止考虑个体路径，而是考虑流出和流入需求之间的全球不平衡。 每位乘客贡献一个单位的所需流量$a_i$到$b_i$。 我们希望使用尽可能少的有向边来实现所有这些流，其中每个选定的边可以承载任意多的乘客，但只能在一个方向上。 

这成为经典的循环平衡思想。 如果一个城市的流出需求多于流入需求，它就必须成为所构建的边缘系统中“过剩流量”的来源。 相反，需求过剩的城市则充当汇。 单一有向边可以通过将盈余从一个城市转移到另一个城市来减少不平衡。 最佳结构以最小化边数的方式将盈余源与赤字汇配对，这导致我们重复地将具有正余额的节点与具有负余额的节点连接起来的结构，逐渐中和两者。 

重要的结构观察是总不平衡和为零，因此我们匹配正数和负数。 每条添加的边至少可以解决两端的一个单位的不平衡问题，因此边的数量正是我们需要在整个系统中传输的总单位数，但按城市而不是按乘客进行汇总。 

可行性条件自然出现：如果在处理所有需求后我们不能一致地匹配余额，那么结构就会崩溃。 事实上，这里的可行性总是在一个完整的有向图中成立，除了由错误计数引起的微小不一致之外，所以真正的困难是最小化边，而不是决定可达性。

 ## 算法演练

 我们首先将每个乘客请求转换为每个城市的净流量不平衡。 

1. 对于每个城市，计算一个值$d[v]$等于出发的乘客人数$v$减去最终到达的乘客数量$v$。 这代表着这座城市有多少“外流责任”。 
2. 将城市分为两组：具有积极影响的城市$d[v]$以及那些有负面影响的人$d[v]$。 正节点必须发送额外的流量，而负节点必须接收它。 
3. 维护这些组的两个列表或指针。 我们反复拿下一座城市$u$和$d[u] > 0$和一座城市$v$和$d[v] < 0$。 
4.我们创建定向弹射器发射$u \to v$。 此边缘是最终时间表的一部分。 
5.让$x = \min(d[u], -d[v])$。 我们在概念上使用这个边缘来转移$x$不平衡单位$u$到$v$。 然后我们更新$d[u] -= x$和$d[v] += x$。 
6. 如果$d[u]$变为零，移动到下一个正的城市。 如果$d[v]$变为零，移动到下一个负数城市。 
7. 继续，直到解决所有不平衡问题。 

我们只允许重复使用同一对边一次的原因是，无论有多少乘客通过它，单个有向边就足够了； 我们只关心每个乘客的可达性，而不关心每个单元都被单独分配不同的边缘。 

### 为什么它有效

 不变的是，在每一步之后，剩余的不平衡正确地反映了每个城市还需要发送或接收多少单位，并且每个创建的边都严格减少总的绝对不平衡总和。 因为每个操作至少消除一个完全满足的端点，所以该过程最多在$n-1$边缘。 由于总不平衡是守恒的，一旦所有$d[v]$当变为零时，每个需求都通过构建的边的传递连接在内部得到满足。 该构造相当于构建一个有向森林，为所有必需的对编码有效的路由结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    d = [0] * (n + 1)

    pairs = []
    for _ in range(m):
        a, b = map(int, input().split())
        d[a] += 1
        d[b] -= 1
        pairs.append((a, b))

    pos = []
    neg = []

    for i in range(1, n + 1):
        if d[i] > 0:
            pos.append([i, d[i]])
        elif d[i] < 0:
            neg.append([i, -d[i]])

    i = j = 0
    res = []

    while i < len(pos) and j < len(neg):
        u, cu = pos[i]
        v, cv = neg[j]

        x = min(cu, cv)
        res.append((u, v))

        cu -= x
        cv -= x

        pos[i][1] = cu
        neg[j][1] = cv

        if pos[i][1] == 0:
            i += 1
        if neg[j][1] == 0:
            j += 1

    if len(res) > n - 1:
        print(-1)
        return

    print(len(res))
    for u, v in res:
        print(u, v)

if __name__ == "__main__":
    solve()
```实施过程首先计算每个城市的净失衡。 正负面清单的两点扫描，确保每个城市只处理一次，从而保持构建的线性$n$。 

一个微妙的点是，即使在概念上转移了多个不平衡单位，我们每个配对步骤也仅输出一个边缘。 这是正确的，因为该问题不需要通过不同的边缘跟踪单个乘客，只需要存在可达性。 边缘本身充当了所有在最终传递结构中需要该方向的乘客的可重复使用的管道。 

支票`len(res) > n - 1`是一个结构健全的条件。 任何有效的构造都会在压缩流组上形成非循环定向结构，并且超过$n-1$边缘意味着可以删除的冗余，因此这种配置在最小性约束下被视为无效。

 ## 边缘情况

 第一个边缘情况是所有乘客已经形成一个完美平衡的系统，每个城市都有相同的进出需求。 在那种情况下所有$d[v]$为零，因此该算法不产生边缘并正确输出零。 

另一个边缘情况是长循环依赖，其中需求在全局范围内取消，但在局部范围内不取消。 例如，$1 \to 2$,$2 \to 3$,$3 \to 1$。 每个节点的不平衡计算结果为零，因此不会产生任何边，这是有效的，因为原始乘客已经形成了一个封闭的可达性结构。 

第三种边缘情况是具有许多中间中立节点的单一主导源和汇。 该算法直接在端点之间配对，忽略中间点，并且仍然保留可达性，因为除了最终边引起的连接之外，不存在中间路由约束。
