 ## 解决方案
 ## 问题理解

 该问题给了我们一个整数数组，并要求我们将其转换为“仙人掌数组”。 仙人掌数组的定义是，对于每个元素，该元素本身要么是局部最大值，要么在经过一些变换后等于前一个元素。 简单来说，我们可以增加一些元素，但不能减少它们，我们的目标是在这些规则下最大化与最终仙人掌数组中的位置相等的元素数量。 

输入由多个测试用例组成。 每个测试用例都以整数开头$n$，数组的长度，后面跟着$n$整数。 对于每个测试用例，输出应报告转换后可以满足仙人掌条件的最大元素数。 

限制条件适中：$n$可以达到$2 \cdot 10^5$跨越所有测试用例，意味着天真$O(n^2)$解决方案会太慢。 我们需要一个大致的解决方案$O(n)$或者$O(n \log n)$每个测试用例。 

当所有元素都相同时，就会出现微妙的边缘情况。 例如，数组`[1, 1, 1]`无需任何操作就已经满足仙人掌条件。 尝试贪婪地增加每个元素的简单方法可能会过度计算转换或产生无效序列。 

当元素严格减少时，会出现另一种棘手的情况。 例如，`[3, 2, 1]`无法转换为完全递增的数组，并且粗心的实现可能会尝试无效的操作。 正确的输出应该遵守“不能减少”规则并只计算可行的变换。 

## 方法

 蛮力方法是尝试所有可能的转换序列。 对于每个元素，我们将尝试增加它以满足仙人掌的要求或保持不变。 这种方法是正确的，因为它探索了每个有效序列，但序列的数量呈指数增长。 为了$n = 10^5$，这会导致操作次数不可行，大致为$O(2^n)$。 

关键的观察结果是，变换问题可以简化为以受约束的方式计算“峰值”。 每个元素要么开始一个新的峰值（如果它严格大于前一个元素），要么继续一个平台期（如果它与前一个元素匹配）。 因为我们只能增加值而不能减少值，所以峰值的数量取决于连续元素之间的差异以及前一个元素是否允许延续。 这种见解将问题简化为简单的线性扫描，每个元素进行一些检查。 

蛮力之所以有效，是因为每个转换都是单个元素的局部转换，但当序列由于指数分支而很长时，就会失败。 认识到我们只需要跟踪“当前峰值”以及最后一个元素是否增加，我们可以将决策空间折叠为$O(n)$。

 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 线性扫描/峰值计数| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.初始化一个计数器`cactus_count`为零。 该变量跟踪满足仙人掌条件的元素数量。 
2. 初始化变量`prev`为零。 这将存储转换后的数组中的最后一个元素。 
3. 从左到右迭代数组。 
4. 对于每个元素`a[i]`，检查是否大于`prev`。 如果是这样，则增加`cactus_count`因为它可能会是一个新的高峰。 
5. 如果`a[i]`等于`prev`，它可以延续之前的平台期，所以增量`cactus_count`。 
6. 更新`prev`为前一个值或当前元素的最大值。 这强制了变换的非递减性质。 
7. 扫描完所有元素后，`cactus_count`包含最大数量的仙人掌元素。 

**为什么它有效**：不变的是`prev`始终表示转换后的数组中的最后一个有效值。 任何大于的元素`prev`开始一个新的峰值，并且任何元素等于`prev`继续高原期。 因为我们从不减少`prev`，我们保证所有变换都是有效的，并且仙人掌元素的计数是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        cactus_count = 0
        prev = 0
        for x in a:
            if x > prev:
                cactus_count += 1
            elif x == prev:
                cactus_count += 1
            prev = max(prev, x)
        print(cactus_count)

if __name__ == "__main__":
    solve()
```该解决方案使用快速 I/O 读取所有输入。 关键部分是扫描一次数组并更新的循环`cactus_count`和`prev`基于峰值/平台规则。 这`max(prev, x)`确保永远不会违反非递减约束。 边界条件（例如大小为 1 的数组或彼此相等的元素）自然由相同的逻辑处理。

 ## 边缘情况

 对于边缘情况`[4, 3, 2, 1]`，算法从左到右扫描。 第一个元素`4`形成一个峰，所以`cactus_count = 1`。 每个后续元素都小于`prev = 4`，所以没有被计算在内。 输出是`1`，这是正确的，因为不允许减少。 

为了`[3, 3, 3]`,`prev`从 0 开始。每个元素等于`prev`或更大，因此所有元素都有助于仙人掌数量。 这证实平台处理是正确的。
