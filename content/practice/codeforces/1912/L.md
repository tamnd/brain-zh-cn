 ## 解决方案
 ## 问题理解

 我们得到一行项目，每个项目要么是“L”，要么是“O”。 目标是在某个位置切断这条线，以便左边的部分由你占据，右边的部分由你的朋友占据。 两个部分都必须非空。 

约束不是关于绝对计数，而是关于两部分之间的比较。 您的分段中“L”项目的数量必须不同于您朋友分段中“L”项目的数量，“O”也必须如此。 我们被要求找到任何有效的剪切位置或报告不存在。 

重新构造此问题的一个有用方法是，我们正在搜索一个前缀，其中两个字符在前缀和后缀之间的计数“不平衡”。 由于一旦我们选择了一个前缀，后缀就完全确定了，所以问题就变成了检查是否存在一个前缀，其字符数不反映任一维度的后缀数。 

约束很小，n 最大为 200。如果需要，这立即允许任何 O(n²) 甚至 O(n³) 推理，但也强烈建议使用前缀信息的线性扫描就足够了。 

一个天真的陷阱是假设总计数的任何不平衡都能保证解决方案。 例如，在像“LOL”这样的字符串中，每次分割都会强制至少一个字符对称分布，从而使所有分割无效。 另一种微妙的失败情况是假设找到前缀计数与总数的一半不同的位置就足够了，这忽略了一个字符仍然可能发生相等而另一个字符不同。 

## 方法

 蛮力的想法很简单。 尝试从 1 到 n - 1 的每个剪切位置 k。对于每个剪切，计算前缀和后缀中的“L”和“O”并进行比较。 每次检查的成本为 O(n)，导致总复杂度为 O(n²)。 当 n = 200 时，这仍然足够小，可以通过，但这是不必要的工作。 

关键的观察是我们可以增量地维护前缀计数。 一旦我们知道“L”和“O”的总计数，我们就可以在恒定时间内导出每次分割的后缀计数。 这将每次检查减少到 O(1)，从而使完整扫描变为 O(n)。 

更深入的结构洞察是，除了前缀积累之外，不同切割位置之间不存在依赖关系。 每个分割都是独立的，并且可以使用运行计数来汇总所有必要的信息。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 已接受 |
 | 前缀扫描 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算整个字符串中“L”和“O”的总数。 这些代表我们选择前缀后朋友将收到的内容。 此步骤是必要的，以便无需重新计算即可导出后缀计数。 
2. 将“L”和“O”的前缀计数器初始化为零。 当我们从左向右扩展剪切位置时，这些将跟踪我们所采取的内容。 
3. 将剪切位置 k 从 1 迭代到 n - 1，通过添加位置 k 处的字符来更新前缀计数器。 我们避免从头开始重新计算，从而保持过程的线性。 
4. 对于每个位置，计算后缀计数为总减去前缀。 这可以为朋友提供准确的分布，而无需扫描后缀。 
5. 检查两个条件：prefix_L ≠ suffix_L 且 prefix_O ≠ suffix_O。 如果两者都成立，则本次切割有效，可以立即退回。 
6. 如果没有位置同时满足这两个条件，则输出-1。 

### 为什么它有效

 在每个位置 k，字符串被划分为两个固定的多重集。 该条件纯粹是这两个多重集之间的计数比较。 由于前缀和后缀计数总和总是等于全局总数，因此一旦知道前缀，就可以完全确定后缀。 因此，独立检查每个 k 涵盖所有可能的有效分区，并且返回第一个有效分区就足够了，因为该问题允许任何答案。

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    total_L = s.count('L')
    total_O = n - total_L

    pref_L = 0
    pref_O = 0

    for i in range(n - 1):
        if s[i] == 'L':
            pref_L += 1
        else:
            pref_O += 1

        suff_L = total_L - pref_L
        suff_O = total_O - pref_O

        if pref_L != suff_L and pref_O != suff_O:
            print(i + 1)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```该解决方案依赖于对字符串的单次传递。 我们首先预先计算总数，以便在恒定时间内导出后缀值。 循环在 n - 1 处停止，因为两边都必须非空。 关键的正确性细节是同时对两个字符进行严格的不平等检查。

 ## 边缘情况

 一种关键的边缘情况是每个前缀至少在一个字符中保留相等性。 对于“LOL”，检查每个剪切结果表明，即使分布发生变化，两个字符之一始终在两侧之间匹配。 

另一个边缘情况是像“LLLLLOOO”这样的统一字符串。 即使在这里，算法也能正确找到有效的分割，除非两个字符同时保持对称性。 前缀-后缀计算确保立即检测到任何不平衡，并且由于我们测试了所有 k，因此不会跳过任何有效的分割。
