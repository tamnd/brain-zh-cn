 ## 解决方案
 ## 问题理解

 我们有一个$n \times m$由单位方块制成的巧克力棒。 切割可以是水平的或垂直的，必须遵循网格线，必须严格位于巧克力内部，并且不能重复先前的切割。 

准确制作后$k$切块时，巧克力被分成几块长方形的块。 在所有生成的碎片中，我们查看面积最小的那一个。 我们的目标是安排切割，使这个最小的区域尽可能大。 

尺寸$n$和$m$可以大到$10^9$， 和$k$可以达到$2 \cdot 10^9$。 这些值立即排除任何剪切模拟或迭代行、列或剪切位置的任何算法。 甚至一个$O(\sqrt{k})$方法将不必要地大。 该解决方案必须仅执行恒定量的算术。 

一个重要的观察结果是，一个具有高度的矩形$n$只有$n-1$可能的水平切割，并且类似地仅$m-1$可能的垂直切割。 不同切割的最大数量是$$(n-1) + (m-1) = n+m-2.$$如果$k > n+m-2$，无法进行所需的切割次数，所以答案是$-1$。 

一些边缘情况很容易被忽略。 

考虑：```
2 3 4
```不同切割的最大数量是$1+2=3$。 四切是不可能的，所以答案是：```
-1
```只尝试优化工件尺寸而不检查可行性的粗心解决方案会产生不正确的正值。 

另一个重要案例是：```
3 4 1
```一次切割时，我们应该尽可能均匀地分割一维。 将宽度切成$2$和$2$给出面积块$3 \times 2 = 6$，这是最优的。 答案是：```
6
```总是切割较长边或总是水平切割的幼稚策略不一定能找到最佳方案。 

另一个更微妙的例子是：```
5 5 8
```自从$n+m-2=8$，必须使用所有可能的切割。 巧克力就变成了$5 \times 5$单位正方形的网格，最小的一块有面积$1$。 任何假设削减仍然可以自由分配的公式在这里都会失败。 

## 方法

 最直接的想法就是尝试每一种可能的水平和垂直切割分布。 

假设我们做$a$水平切割和$b$垂直切割，与$$a+b=k.$$切块后，巧克力被分成$a+1$水平条和$b+1$垂直条。 为了最大化最小的矩形，沿每个维度的条带应尽可能相等。 

如果我们修复了$a$和$b$，我们可以计算出最大可能的最小高度和宽度，然后得到最小的矩形面积。 尝试每个有效值$a$会找到最优的。 

困难在于$k$可以在附近$2 \cdot 10^9$。 枚举所有可能的值$a$是完全不可能的。 

关键的观察结果是，原始的 Codeforces 问题隐藏了更强大的结构。 

假设我们决定花费$x$垂直方向切割。 这些切口分割了宽度$m$进入$x+1$件。 最大可能的最小宽度是$$\left\lfloor \frac{m}{x+1} \right\rfloor.$$同样，如果我们花费$y$水平方向切割，最大可能的最小高度为$$\left\lfloor \frac{n}{y+1} \right\rfloor.$$自从$x+y=k$，最小块面积变为$$\left\lfloor \frac{m}{x+1} \right\rfloor \cdot \left\lfloor \frac{n}{k-x+1} \right\rfloor.$$乍一看，这看起来仍然是一个巨大的搜索空间。 

决定性的观察是，官方解决方案只需要检查两种可能性。 

如果最终最小的块的宽度是通过分割确定的$m$，那么垂直线段的数量必须是某个类似除数的数量。 重新安排优化表明，一个维度必须吸收创建所需数量的线段所需的所有切割，而另一个维度则保持未切割。 这将搜索减少为两个候选结构：

 首先，使用$k$削减创造$k+1$沿宽度分段。 所得的最小块面积为$$n \cdot \left\lfloor \frac{m}{k+1} \right\rfloor.$$二、使用$k$削减创造$k+1$沿高度分段。 所得的最小块面积为$$m \cdot \left\lfloor \frac{n}{k+1} \right\rfloor.$$因为只有$n-1$水平切割和$m-1$垂直削减是存在的，我们必须尊重这些限制。 表达这一点的标准方式是逆向思考。 

如果我们花$x$在一个维度上进行切割，然后我们创建$x+1$段。 段数永远不能超过尺寸长度。 

尝试两种可行的分配会得出众所周知的公认解决方案：

 - Use$n$作为未触及的维度和鸿沟$m$进入$k+1$部分。 
- 使用$m$作为未触及的维度和鸿沟$n$进入$k+1$部分。 

在实现中，这变成检查在尺寸之间分配切割的两种可能的方法，同时尊重切割限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(k)$|$O(1)$| 太慢了 |
 | 最佳|$O(1)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 阅读$n$,$m$， 和$k$。 
2. 检查是否$k > n+m-2$。 

如果为真，则输出$-1$因为没有足够的清晰内部网格线可用于那么多切割。 
3. 将答案初始化为$0$。 
4.考虑使用$n-1$或更少的水平切割，其余的垂直切割。 

如果$k < n$，那么我们就可以花掉所有的$k$沿高度方向切割。 这创造了$k+1$水平线段，因此最小高度变为$$\left\lfloor \frac{n}{k+1} \right\rfloor.$$宽度保持不变$m$，给出候选区域$$m \cdot \left\lfloor \frac{n}{k+1} \right\rfloor.$$5. 考虑对称结构。 

如果$k < m$，那么我们就可以花掉所有的$k$沿宽度方向切割。 候选区域变为$$n \cdot \left\lfloor \frac{m}{k+1} \right\rfloor.$$6.还有一种可能。 如果我们首先在一个维度中使用所有可用的切割，则剩余的切割必须放置在另一个维度中。 

什么时候$k \ge n$，我们可以使用$n-1$水平切割，留下$$k-(n-1)$$切割宽度。 最小面积变为$$\left\lfloor \frac{m}{k-n+2} \right\rfloor.$$7. 对称地，当$k \ge m$，另一个候选者是$$\left\lfloor \frac{n}{k-m+2} \right\rfloor.$$8.输出得到的最大候选。 

### 为什么它有效

 每一次切割都只贡献一个维度。 如果一个维度接收到$t$切，它分为$t+1$段，最大可能的最小段长度是尺寸长度除以的整数商$t+1$。 

对于固定数量的切割，最大化最小矩形相当于最大化每个受影响维度中的最小线段长度。 当一个维度接受尽可能多的切割，而剩余的所需切割被迫进入另一维度时，就会出现最佳排列。 这些正是算法检查的候选结构。 任何其他分布产生的最小边长不大于这些极端情况之一，因此候选的最大值是最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    if k > n + m - 2:
        print(-1)
        return

    ans = 0

    if k < n:
        ans = max(ans, (n // (k + 1)) * m)

    if k < m:
        ans = max(ans, (m // (k + 1)) * n)

    if k >= n:
        ans = max(ans, m // (k - n + 2))

    if k >= m:
        ans = max(ans, n // (k - m + 2))

    print(ans)

solve()
```第一个条件处理不可能性。 一个长方形的大小$n \times m$仅包含$n-1$水平切割线和$m-1$垂直切割线，因此除此之外不存在任何解决方案$n+m-2$削减。 

接下来的两个分支对应于在一维上花费所有削减。 因素$k+1$出现是因为$k$削减创造$k+1$段。 

最后两个分支处理一维耗尽可用切割位置的情况。 例如，使用完所有后$n-1$水平切口，其余切口必须沿宽度方向。 分母变为$$k-(n-1)+1 = k-n+2.$$差一是这个问题中最常见的实现错误。 

Python 整数自动处理高达$10^{18}$，因此不存在溢出问题。

 ## 边缘情况

 考虑：```
2 3 4
```该算法首先检查是否$$k > n+m-2.$$自从$$4 > 2+3-2 = 3,$$它立即输出$-1$。 不评估候选公式。 当无法实际进行所需的切割时，这可以防止产生无意义的正区域。 

考虑：```
1 10 5
```没有可用的水平切割。 算法进入分支$k \ge n$, 给予$$10 // (5-1+2)=10//6=1.$$答案是$1$，这与只能进行垂直切割的事实相匹配。 

考虑：```
5 5 8
```必须使用所有可用的切割线。 该算法评估$$5 // (8-5+2)=1,$$来自对称分支和返回$1$。 这正确地捕捉到了每个单位正方形都成为自己的一块的情况。 

考虑：```
3 4 1
```该算法比较两种可能的单向分割：$$(3 // 2)\cdot4=4,$$和$$(4 // 2)\cdot3=6.$$它返回$6$，表明最好的答案不一定是通过切割较高的维度来获得的。
