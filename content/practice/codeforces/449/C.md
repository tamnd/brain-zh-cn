 ## 解决方案
 ## 问题理解

 我们的苹果编号为`1`到`n`。 我们希望创建尽可能多的不相交对，使得每对中的两个数字的最大公约数大于`1`。 

每个苹果最多可以出现一对。 任务不是计算最大配对数，而是显式输出一个最佳配对。 

约束条件`n ≤ 100000`是中心难点。 数字多达十万个，因此任何检查所有对的算法都是不可能的。 可能的对的数量大约是$$\frac{n(n-1)}{2} \approx 5 \cdot 10^9$$什么时候`n = 100000`，这远远超出了一秒钟可以处理的范围。 

条件的结构才是真正的线索。 只要两个数字共享一个质因数，它们就可以配对。 由于涉及整除性和素因数，因此可能需要基于筛的数论构造。 

一些边缘情况很容易处理不当。 

考虑：```
1
```只有一个苹果，所以不能组成一对。 正确答案是：```
0
```任何假设每个数字都属于某个除数组的实现都会在这里失败。 

考虑：```
3
```数字是`{1,2,3}`。 数字`1`不能与任何东西配对，因为`gcd(1,x)=1`对于每一个`x`。 正确答案是：```
0
```试图将每个剩余数字配对的贪婪策略会错误地尝试使用`1`。 

考虑：```
6
```数字是`{1,2,3,4,5,6}`。 

粗心的贪婪方法可能会配对`(2,6)`首先，离开`{3,4}`未使用。 自从`gcd(3,4)=1`，仅获得一对。 

最优解产生两对，例如：```
6 3
2 4
```挑战不仅在于找到有效的对，还在于对它们进行排列以使对的总数最大。 

## 方法

 最直接的想法就是构建一个图。 为每个数字创建一个顶点`1`到`n`，如果两个顶点的 gcd 大于，则连接两个顶点`1`。 问题就变成了寻找最大匹配。 

这是正确的，因为每个有效的配对对应于一条边，并且不相交的对对应于匹配的边。 

不幸的是，这个图表太大了。 即使建造它也需要粗略地检查`n²/2`对。 为了`n = 100000`，这意味着数十亿次 gcd 计算。 一般的最大匹配算法是完全不可行的。 

关键的观察结果是该图具有非常特殊的结构。 两个数字是否可以配对取决于共享的质因数。 不要考虑任意边缘，而是考虑按整除性分组的数字。 

假设我们从最大到最小处理素数。 对于素数`p`，考虑所有当前未使用的数字可被整除`p`。 

该集合中的每两个数字自动具有至少 gcd`p`，因此集合内的任何对都是有效的。 

剩下的挑战是避免不同素数之间的冲突。 像这样的数字`30`同时属于许多素数群。 

经典的 Codeforces 解决方案通过按降序处理素数并标记分配后使用的数字来处理此问题。 处理素数时`p`，我们收集所有仍未使用的倍数`p`。 

如果计数是偶数，我们只需将它们任意配对即可。 

如果计数为奇数，则必须排除一个数字。 对于奇数素数，被排除的数是`2p`。 这个选择是非常经过深思熟虑的。 自从`2p`是偶数，稍后可以在素数下进行处理`2`，它仍然可以参与另一对。 每隔一个倍数`p`大于`2p`包含`p`作为其最大的质因数，否则将永远丢失。 

从最大到最小处理素数可以保证在考虑每个数字的最大素因数时对其进行处理。 这可以防止未来的冲突并产生最大可能数量的对。 

为了有效地生成素数和最大素数因子信息，我们使用筛子。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力匹配| O(n²) 或更糟 | O(n²) | 太慢了 |
 | 筛子+建设性配对| O(n log log n) | O(n log log n) | O(n) | 已接受 |

 ## 算法演练

 1. 建造一个筛子`n`并计算每个数字的最大素因数。 
2. 提取所有素数并按降序处理。 
3. 维护一个布尔数组`used`，指示某个号码是否已分配给一对。 
4. 对于当前的素数`p`，收集所有未使用的倍数`p`。 

这些正是仍然可以通过质因数配对的数字`p`。 
5. 如果收集到的计数为偶数，则将连续元素配对。 

每对都是有效的，因为两个数字都可以被整除`p`。 
6. 如果收集到的计数为奇数且`p > 2`，删除数字`2p`从列表中。 

剩余计数变为偶数。 

选择的理由`2p`是它可以稍后参与素数的处理`2`，而删除任何其他倍数会浪费最大素因数为的数字`p`。 
7. 将剩余的数字一次配对两个，并将它们全部标记为已使用。 
8. 继续，直到处理完每个素数。 
9. 输出所有构造对。 

### 为什么它有效

 当遇到一个数字的最大质因数时对其进行处理。 

假设一个数字`x`有最大的素因数`p`。 当素数大于`p`被处理，`x`不被考虑，因为它不能被它们整除。 当素数时`p`被处理，`x`出现在未使用的倍数中`p`。 

如果计数为偶数，`x`立即配对。 

如果计数为奇数，则仅`2p`可能会被推迟。 具有最大质因数的所有其他数字`p`在此阶段进行配对。 特别的选择`2p`保留未来的配对机会，因为它也属于素数下处理的偶数组`2`。 

因此，除了不可避免的剩余数之外，每个可能的数字都只匹配一次。 官方解决方案中使用的构造达到了最大匹配尺寸。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    lp = [0] * (n + 1)

    for i in range(2, n + 1):
        if lp[i] == 0:
            for j in range(i, n + 1, i):
                lp[j] = i

    primes = [i for i in range(2, n + 1) if lp[i] == i]

    used = [False] * (n + 1)
    ans = []

    for p in reversed(primes):
        cur = []

        for x in range(p, n + 1, p):
            if not used[x]:
                cur.append(x)

        if len(cur) & 1:
            if p == 2:
                cur.pop()
            else:
                cur.remove(2 * p)

        for i in range(0, len(cur), 2):
            a = cur[i]
            b = cur[i + 1]
            ans.append((a, b))
            used[a] = True
            used[b] = True

    print(len(ans))
    for a, b in ans:
        print(a, b)

if __name__ == "__main__":
    solve()
```筛子存储每个数字的最大素因数。 与通常的最小素数因子筛不同，我们在遍历过程中故意覆盖值，因此最终存储的素数是最大除数素数。 

素数按降序处理。 这种排序是构造的核心，因为它让每个数字在达到其最大素因数时得到处理。 

对于素数`p`, 列表`cur`包含所有未使用的倍数`p`。 此列表中的每个元素都可以安全地与同一列表中的任何其他元素配对。 

奇特尺寸的外壳是微妙的部分。 对于大于二的素数，去掉`2p`保留最大值。 什么时候`p = 2`，没有剩余的更小的素数，因此必须丢弃一个剩余的数字。 

配对循环从以下位置获取相邻元素`cur`。 不需要特殊的匹配策略，因为列表中的每一对都已经满足 gcd 条件。 

## 工作示例

 ### 示例 1

 输入：```
6
```处理顺序是`3`， 然后`2`。 

| 总理 p | 未使用的倍数 | 调整| 生产对 |
 | --- | --- | --- | --- |
 | 3 | {3,6} | 无 | (3,6) |
 | 2 | {2,4} | 无 | (2,4) |

 输出：```
2
3 6
2 4
```此示例显示了如何通过可以处理它们的最大素因数来声明数字。 后`(3,6)`已创建，编号`6`不再适用于 Prime`2`。 

### 示例 2

 输入：```
10
```| 总理 p | 配对前未使用的倍数 | 调整| 生产对 |
 | --- | --- | --- | --- |
 | 7 | {7} | 删除 7 | 无 |
 | 5 | {5,10} | 无 | (5,10) |
 | 3 | {3,6,9} | 删除 6 | (3,9) |

该跟踪说明了为什么删除`2p`很重要。 数字`6`在黄金期间被推迟`3`处理并随后在 Prime 下成功配对`2`。

 ## 边缘情况

 ### 单个苹果

 输入：```
1
```不进行素数处理，因为没有素数达到`1`。 

答案列表仍为空：```
0
```这证实了该算法并未尝试使用苹果`1`，其与其他所有数字的 gcd 为`1`。 

### 奇素数的奇数倍计数

 输入：```
10
```在处理素数过程中`3`，未使用的倍数为：```
{3, 6, 9}
```计数为奇数。 该算法去除了`6 = 2 × 3`，生产：```
{3, 9}
```形成一对。 

后来在巅峰时期`2`， 数字`6`仍然可用，并且可以与另一个偶数配对。 删除任何其他元素将永久失去匹配机会。 

### 大于 n/2 的素数

 输入：```
7
```对于总理`7`，唯一的倍数是：```
{7}
```无法形成配对。 

该算法只是将其从考虑中丢弃。 这是不可避免的，因为没有第二个数字可以被`7`在范围内`1..7`。 

剩下的素数继续正常进行，最终的答案仍然是最优的。
