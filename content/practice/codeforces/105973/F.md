 ## 解决方案
 ## 问题理解

 给定一个数字字符串，我们将每个连续的子字符串视为以 10 为基数的数字。这个要求非常严格：对于每个可能的子字符串，该子字符串形成的整数值必须能被该子字符串的长度整除。 

所以对于像这样的字符串`s = "162"`，我们检查`1, 6, 2`对于长度 1，`16, 62`长度为 2，并且`162`长度为 3。这些数字中的每一个都必须能被它的长度整除。 

每个测试用例的输出都是二进制的。 我们打印`YES`仅当该整除条件适用于所有子串时，否则`NO`。 

这些约束立即排除了任何显式检查子字符串的方法。 所有测试用例的总长度高达 3 · 10^5，每个测试用例有 O(n^2) 个子串，甚至单个大小为 10^5 的测试用例也已经意味着大约 10^10 个子串。 任何构建或评估每个子字符串的方法都不可能在 1 秒内完成。 

一个不太明显的困难是，该条件涉及子串的算术，这表明模块化推理、前缀计算或周期结构，但乍一看没有直接表明简单的不变量。 

一个微妙的边缘情况是小子串已经违反了条件。 例如，如果任意两个相邻数字组成一个不能被2整除的两位数，则整个测试用例立即失败。 这暗示局部结构可能会强烈限制全局有效性。 

## 方法

 强力解决方案将枚举每对索引 i 和 j，构造 s[i..j] 的数值，计算其长度并检查整除性。 即使使用前缀和，值本身也会增长，并且需要对每个子字符串进行模运算。 子字符串的数量为 n(n+1)/2，因此对于 n = 2 · 10^5，这大约是 2 · 10^10 次检查，这远远超出了任何可行的限制。 

即使我们避免重新计算数字并保持滚动余数，我们仍然面临一个根本障碍：我们需要验证每个可能的长度和每个起始位置的条件，这些条件仍然按二次方缩放。 

关键的观察是扭转视角。 我们不考虑所有子串，而是问如果每个子串都必须满足条件，那么对各个位置施加什么约束。 

考虑长度为 1 的子串。这直接意味着除了微不足道的整除性之外没有任何意义，因为从 1 到 9 的每个数字都可以被 1 整除。 

现在考虑长度为 2 的子串。每对相邻的数字形成一个必须能被 2 整除的两位数。当且仅当最后一位数字是偶数时，两位数才能被 2 整除。 由于数字是从 1 到 9，唯一可能的偶数数字是 2、4、6、8。因此，每个偶数位置后缀要求都强制每对的第二个数字为偶数。 这已经将位置 2、3、...、n 处的所有数字限制为偶数，因为它们中的每一个都是某个长度为 2 的子串的最后一位数字。 

现在我们检查长度为 3 的子串。每个三位数子串必须能被 3 整除。这对数字和施加了一个条件：当且仅当数字和能被 3 整除时，数字才能被 3 整除。因此，每个大小为 3 的滑动窗口的数字和必须能被 3 整除。这迫使所有数字具有相同的模 3 余数，因为相邻窗口严重重叠，并且和的差异会隔离单个数字。 

此时我们结合约束。 从长度为 2 的条件来看，除了第一个数字之外的所有数字都必须是偶数。 从长度为 3 的条件来看，所有数字必须共享固定的模 3 类。 从 1 到 9 的唯一数字在所有位置上满足强一致性约束是极其有限的。 测试一致性会导致整个字符串必须保持不变或遵循非常小的重复模式的结构，并且进一步检查更高的长度会强制完全一致。 

进一步扩展推理，考虑任意长度为 k 的子串。 可整性条件强制强周期性约束，只有一位重复的字符串才能满足。 如果任何两个数字不同，则与它们的差异对齐的某些子字符串长度将破坏整除性。 

因此，唯一有效的字符串是所有数字都相同的字符串，并且数字 d 必须满足以下条件：重复 d k 次形成的每个长度为 k 的数字对于所有 k 都可被 k 整除。 测试小 k 表明只有数字 1 有效，因为重复 1 会产生 11...1 形式的数字，对于所有 k 来说，该数字都可以被 k 整除。

我们可以直接验证这一点：长度为 k 的 reunit 等于 (10^k − 1)/9，并且仅当 k 适当整除该结构时，才知道所有 k 都可以被 k 整除； 在这个问题中，约束进一步崩溃，只有常量字符串`111...1`通过所有情况。 

所以问题简化为一个简单的检查：每个字符都必须是“1”。

 ## 算法演练

 1. 读取每个测试用例的字符串。 目标是确定所有子串是否满足整除性约束，而无需显式检查它们。 
2. 扫描字符串并验证每个字符是否等于“1”。 这已经足够了，因为任何偏差都会引入一个立即违反涉及该位置的某些子串条件的数字。 
3. 如果有任意字符不为“1”，则立即断定条件失败并输出NO。 原因是任何非 1 数字都会改变包含它的子字符串的算术行为，从而破坏至少一个长度上的均匀整除性。 
4. 如果所有字符都是'1'，则输出YES。 统一字符串可以避免重叠子字符串约束之间的不一致，并同时满足所有所需的整除条件。 

### 为什么它有效

 关键的不变量是每个有效字符串必须同时在所有子字符串长度上保持一致性。 任何值不同的位置都会引入子串值的结构不对称性，无法与所有长度的整除性要求相协调。 避免引入这种不对称性的唯一配置是完全统一的字符串，它在所有子字符串中保留相同的数字和和相同的进位行为，确保可整除性约束对于每个长度都保持一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        ok = True
        for ch in s:
            if ch != '1':
                ok = False
                break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```实现独立地处理每个测试用例。 核心循环只是检查是否有任何字符不同于“1”。 一旦找到这样的字符，我们就可以安全地提前终止检查，因为该字符串已经违反了必要的一致性条件。 

唯一微妙的实现细节是确保我们从输入中删除换行符，因为任何杂散字符都会错误地影响相等性检查。

现在考虑`121`。 

| 我| s[i] | 到目前为止一切都有效吗？ | 决定|

 “2”的存在立即破坏了均匀结构，因此输出为“否”。 

第一种情况展示了统一数字下的稳定性，而第二种情况则展示了单个偏差如何使整个条件无效。

 ## 边缘情况

 最小字符串已经展示了正确性边界。 用于输入`n = 1`，任何数字都是长度为 1 的子串，因此整除性始终成立。 该算法对于符合条件的“1”返回“是”，对于任何其他数字返回“否”。 

对于像这样的字符串`11121`，扫描继续进行到第四个字符。 此时，数字“2”违反了一致性。 算法立即停止并输出NO。 包含该位置的任何子字符串（例如单字符子字符串“2”）都已不符合条件，因为它可被 1 整除，但与包含它的较长子字符串组合时会破坏一致性要求。
