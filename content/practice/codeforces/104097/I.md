 ## 解决方案
 ## 问题理解

 我们得到一个由位掩码索引的数组。 每个位置代表某个大小宇宙的子集$k$，所以有$2^k$总计值。 任务是为每个子集计算通过包含与其相关的其他子集的聚合。 在称为“子集加子集之和”的版本中，掩码的值通常是掩码包含在其中的所有值的总和，尽管相同的框架也以相反的方式出现，其中超集被聚合。 

输出是另一个相同大小的数组，其中每个位置都回答其相应掩码的聚合查询。 

核心困难在于每个查询都依赖于指数级的许多其他掩码。 直接解释会导致跨重叠集的重复工作，这正是问题旨在揭示的内容。 

约束隐含地围绕$2^k$。 如果$k$约为 20 或 22，则完整数组大小约为一百万到几百万个条目。 这立即排除了任何尝试为每个掩码独立枚举子集的方法，因为这会导致类似的结果$O(4^k)$，这远远超出了可行的限度。 预期的解决方案必须重用部分计算并利用跨位掩码的结构。 

常见的边缘情况出现在以下情况：$k = 0$。 在这种情况下，只有一个子集，即空掩码，并且答案必须与输入简单匹配。 另一种微妙的情况是，除了一个位置之外，所有值都为零。 如果位转换处理不正确，则简单的子集枚举很容易过度计数或错过贡献，特别是如果实现混合了子集和超集方向。 

## 方法

 暴力破解的想法很简单：对于每个掩码，迭代所有子掩码并对它们的值求和。 这是正确的，因为它直接遵循所需聚合的定义。 然而，掩码的子掩码数量为$2^{\text{popcount}(mask)}$，并将所有掩模的总和得出大约$3^k$运营。 为了$k = 20$，这已经是$3^{20} \approx 3.4 \times 10^9$，这太慢了。 

关键的观察结果是计算严重重叠。 当从一个掩码移动到另一掩码时，大部分子掩码结构是共享的。 我们可以通过逐渐允许更多位参与来逐步构建答案，而不是从头开始重新计算。 

这正是 SOS DP“子集求和动态规划”的设置。 这个想法是一位一位地处理位，并逐步放松对允许哪些位变化的限制。 处理后$i$-th 位，我们知道正确答案仅考虑较低的$i$自由位，我们将其扩展到包括位$i$同时保留所有较小位的正确性。 

暴力破解之所以有效，是因为它显式枚举了所有子掩码。 它失败了，因为这个枚举对于每个掩码都是独立重复的。 SOS DP 将其简化为$k \cdot 2^k$通过确保每个子集关系在每个位级别精确地考虑一次来进行转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(3^k)$|$O(2^k)$| 太慢了|
 | SOS DP |$O(k \cdot 2^k)$|$O(2^k)$| 已接受 |

 ## 算法演练

 我们维护一个 DP 数组，其中`dp[mask]`最初存储该子集的给定值。 目标是对其进行改造，以便每个`dp[mask]`累积所有子掩码的贡献。 

1. 初始化`dp[mask]`与所有掩码的输入值。 这代表尚未应用聚合的基本情况。 
2.迭代从0到的每个位位置$k-1$。 每次迭代都允许信息沿着该位定义的子集网格的一个维度流动。 
3. 对于每个掩码，检查当前位是否已设置。 如果未设置，我们可以安全地使用此掩码作为基本状态，以组合来自仅此位不同的相关掩码的信息。 
4. 执行转换`dp[mask] += dp[mask with bit set]`对于子集和变体。 此步骤有效地表明，包含当前结构加上此附加位的所有子集都对当前掩码的答案做出了贡献。 
5. 对所有位重复此过程，以便贡献在所有可能的位组合中传播。 

迭代的顺序仅在确保每个维度在移动到下一个维度之前得到充分处理方面才重要。 完成所有位后，每个掩码在每个有效转换路径上都累积了来自所有相关掩码的贡献一次。 

### 为什么它有效

 处理完第一个数据后DP的状态$i$位表示仅考虑这些位的所有子集的正确聚合。 不变的是任何一对仅在位上不同的掩码大于$i$已经正确合并了他们的贡献。 

处理位时$i$，我们合并仅在那一点不同的状态，将正确性从布尔格子的较小子立方体扩展到较大的子立方体。 由于每个子集关系都可以分解为一系列位翻转，因此每个贡献都通过一个有效的链传播，从而防止重复或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    dp = list(map(int, input().split()))
    
    k = n.bit_length() - 1 if n & (n - 1) == 0 else n.bit_length()
    
    # If input size is 2^k, we infer k from n
    # but more safely, treat k as bit width of indices
    # (common CF format gives n = 2^k directly)
    
    k = (n - 1).bit_length()
    
    for i in range(k):
        for mask in range(n):
            if mask & (1 << i):
                dp[mask] += dp[mask ^ (1 << i)]
    
    print(*dp)

if __name__ == "__main__":
    solve()
```该代码首先读取数组的大小，假设该数组是一个完整的幂集，然后是与每个子集关联的值。 DP 数组直接从输入初始化。 

主循环独立处理每一位。 对于包含当前位的每个掩码，我们添加来自删除该位的同一掩码的贡献。 这个方向确保我们从子掩码累积到超集，这与预期的子集和累积相匹配。 

的计算`k`导出表示所有掩码所需的位数。 由于数组大小是$2^k$，我们恢复$k$使用位长度逻辑。 一个常见的陷阱是假设$n$已经是$k$，这会完全破坏索引。

 ## 边缘情况

 对于$k = 0$，只有一个掩码，即空集。 该算法对位执行零迭代，因此原始值打印不变。 例如，输入`1\n5`回报`5`，它符合定义，因为空宇宙的唯一子集就是它本身。 

当所有掩码中仅设置一位时，传播仅沿该维度发生。 DP 正确地累加值而不受其他位的干扰，因为沿未设置的维度不存在转换。 

一个棘手的情况是当值稀疏但位于较高索引的掩码中时。 该算法仍然可以正确传播，因为每个位都是独立处理的，并且较高位仅影响明确包含它们的状态。
