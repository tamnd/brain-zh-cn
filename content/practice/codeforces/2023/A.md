 ## 解决方案
 ## 问题理解

 我们被给予`n`数组，每个数组恰好包含两个数字。 我们可以按照我们想要的任何方式对这些数组进行重新排序，但在每个数组内部，两个元素的顺序必须保持不变。 

选择顺序后，我们连接所有数组并获得一个长度的序列`2n`。 我们的目标是选择最小化最终序列中反转次数的顺序。 

关键细节是我们没有被要求计算最小反转次数。 我们只需要输出实现它的任何串联顺序。 

所有测试用例的数组总数最多为`10^5`。 这立即排除了任何检查许多排列的情况。 即使检查数组之间的所有成对关系也只能勉强接受，而任何阶乘关系都是没有希望的。 解决方案围绕`O(n log n)`每个测试用例是自然目标。 

有几种容易被忽略的情况。 

考虑元素已经在增加的数组：```
2
1 100
2 3
```一个天真的想法可能是按第一个元素排序。 这给出了`[1,100] [2,3]`，产生许多跨数组反转，因为`100`比两者都大`2`和`3`。 最优顺序实际上是`[2,3] [1,100]`。 

另一个微妙的情况是当数组递减时：```
2
5 1
4 2
```每个数组已经贡献了一个不可避免的内部反转。 由于内部顺序无法更改，因此我们唯一可以优化的是不同数组之间创建的反转。 

同等价值也很重要：```
2
1 1
1 1
```相同的数字永远不会产生反转。 任何正确的排序都应该自然地处理关系，而不引入特殊的逻辑。 

最后，像这样的数组```
3
100 1
2 3
4 5
```说明为什么仅查看第一个元素或仅查看第二个元素是不够的。 每个数组内两个值之间的交互决定了正确的排序规则。 

## 方法

 蛮力方法很简单。 尝试每一个排列`n`数组，构建结果序列，计算反转，并保持最佳排列。 

这是正确的，因为它明确检查所有可能的订单。 

The problem is the number of permutations. 即使是为了`n = 10`, 已经有`10! = 3,628,800`的可能性。 实际限制是`10^5`，所以暴力破解是完全不可行的。 

要找到更好的策略，请关注反转的来源。 

每个数组仅包含两个元素。 假设我们有两个数组：```
A = [a1, a2]
B = [b1, b2]
```如果我们放置`A`前`B`，这对贡献的跨数组反转是```
[a1 > b1] + [a1 > b2] + [a2 > b1] + [a2 > b2]
```在哪里`[condition]`是`1`当为真且`0`否则。 

如果我们改为放置`B`前`A`，贡献变为```
[b1 > a1] + [b1 > a2] + [b2 > a1] + [b2 > a2]
```每个数组的内部反转永远不会改变，因此只有这些成对的交叉贡献才重要。 

一个有用的观察是，如果我们在概念上按每个数组的较小值和较大值对每个数组进行排序，```
low = min(x, y)
high = max(x, y)
```然后通过对数组进行排序来获得最佳排序`low`。 

这正是官方解决方案中使用的顺序。 另一个等效的公式是对数组进行排序`min(ai)`。 

为什么这有效？ 

取两个数组`A`和`B`。 

如果```
min(A) <= min(B)
```放置`A`前`B`永远不会比放置更多的交叉反转`B`前`A`。 成对比较简化为交换论证。 每当两个相邻数组违反此顺序时，交换它们不会增加总反转计数。 反复应用此类交换会导致全局最优安排。 

一旦知道了这个排序标准，整个问题就变成了排序问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!·n²) | O(n!·n²) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取所有数组及其原始两个值。 
2. 对于每个数组，计算其最小元素。 
3. 按此最小元素升序对数组进行排序。 

交换参数表明，只要两个相邻数组不符合此顺序，交换它们就不会增加反转次数。 
4. 按排序顺序输出数组，保留每个数组内两个元素的原始顺序。 
5. 将所有打印对连接成一个序列。 

### 为什么它有效

 总反转计数由两部分组成。 

第一部分是完全在各个数组内进行反转。 由于每对内部的顺序是固定的，因此这些反转是恒定的并且无法优化。 

第二部分是不同数组之间的反转。 对于任意两个数组，它们的贡献仅取决于哪个数组先出现。 如果两个相邻数组的排列顺序与其最小元素的递增顺序相反，则交换它们永远不会增加它们的成对贡献。 由于所有其他对保持不变，因此交换后总反转计数不会增加。 

在排序中反复修复此类反转，最终会产生按最小元素排序的序列。 由于每次局部互换都是不增加的，因此最终的安排是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n = int(input())

        arr = []
        for _ in range(n):
            x, y = map(int, input().split())
            arr.append((min(x, y), x, y))

        arr.sort(key=lambda item: item[0])

        res = []
        for _, x, y in arr:
            res.append(str(x))
            res.append(str(y))

        out.append(" ".join(res))

    sys.stdout.write("\n".join(out))

solve()
```第一步将每对及其最小值存储在一起。 该最小值是从交换参数派生的排序键。 

排序后，我们必须完全按照给定输出原始对。 一个常见的错误是对一对内的两个数字重新排序。 该问题仅允许对整个数组重新排序，而不允许修改其内容。 

这些值可以大到`10^9`，但我们只比较并打印它们。 没有算术超出`min()`是必需的，因此溢出永远不是问题。 

所有测试用例的数组总数最多为`10^5`， 制作`O(n log n)`排序很容易，足够快。
