 ## 解决方案
 # 问题理解

 该问题描述了一个带权无向图的旅程。 顶点是位置，边是道路，每条道路都有旅行时间。 您从一个位置开始并想要到达另一个位置。 有些地方有避难所。 每当到达避难所时，雨中行走的累计时间就会为零。 

限制与总行程长度无关。 它涉及休息之间的每一次连续旅行。 一条有效的路线可以有很多长的部分，只要从起点或避难所到下一个避难所或目的地的每个部分的总边权重最多`k`。 

输入包含多个图形实例。 对于每个实例，我们都会收到顶点和边的数量、降雨限制、起点和目的地顶点、避难所顶点集和加权边。 输出询问是否可以在不超过允许的连续行驶时间的情况下到达目的地。 

所有测试用例的顶点和边的总数最多为`2 * 10^5`。 这排除了从每个避难所重复运行最短路径算法或枚举避难所对的解决方案。 解决方案围绕`O((n + m) log n)`是合适的，因为它对每个顶点和边执行少量对数工作。 

棘手的情况是由于将总路径长度与连续行程长度混淆而引起的。 例如：```
3 2 4
1 3
1
2
1 2 3
2 3 3
```正确的输出是：```
NO
```粗心的最短路径解决方案会看到一条长度的路径`6`如果它仅与更大的全局限制进行比较，则可能会接受它。 旅行者到达顶点的避难所`2`只有在消费之后`3`单位，但第二条边也花费`3`，所以整个行程无效，因为极限是`4`。 

另一个重要的情况是当目的地本身是避难所时：```
2 1 5
1 2
1
2
1 2 5
```正确的输出是：```
YES
```正好在极限处到达目的地。 避难所随后重置计数器并不重要，因为到达那里就已经完成了旅程。 

最后一个边缘情况是没有庇护所：```
2 1 10
1 2
0

1 2 7
```正确的输出是：```
YES
```唯一可能的路段是整条路线，因此直达旅行时间必须在`k`。 

# 方法

 一种直接的方法是首先找到重要顶点之间的每对最短距离，其中重要顶点是起点、终点和避难所。 然后我们可以构建另一个图，其中两个重要顶点相连，如果它们之间的最短距离最多为`k`。 最后，我们将在这个较小的图中检查可达性。 

这个想法是正确的，因为从一个重要顶点移动到另一个重要顶点正好代表一个连续的雨段。 问题是可以有`n`庇护所。 从每个避难所运行 Dijkstra 需要`O(n(n+m)log n)`最坏情况下的时间，远远超出了限制。 

关键的观察是我们不需要显式地构建庇护所图。 我们只需要知道哪些顶点是可到达的，同时跟踪当前的连续旅行时间。 当我们到达避难所时，该值立即又变为零。 

这导致了修改后的 Dijkstra 搜索。 为顶点存储的距离不是从起点开始的总行进距离。 这是站在该顶点所需的最小不间断降雨时间。 值越小越好。 从具有当前值的顶点`d`，我们可以遍历权重的边`w`仅当`d + w <= k`。 如果该边的目标顶点是避难所，则新值将变为零。 否则，新值将变为`d + w`。 

蛮力方法在搜索之前计算所有可能的安全转换。 最佳方法准确地发现在一个图遍历过程中重要的转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n(n+m)log n)`|`O(n+m)`| 太慢了|
 | 最佳 |`O((n+m)log n)`|`O(n+m)`| 已接受 |

 ## 算法演练

 1. 标记每个庇护所顶点，以便算法可以立即知道到达顶点是否会重置降雨计时器。 重要的区别在于站在正常顶点和站在避难所之间。 
2. 初始化一个距离数组，其中`dist[v]`表示到达顶点所需的最小连续降雨时间`v`。 将起始顶点设置为零，因为尚未发生任何旅行。 将其放入优先队列中。 
3. 重复从优先级队列中取出当前下雨时间最小的顶点。 如果此条目已过时，请忽略它。 这是与 Dijkstra 一起使用的标准惰性删除技术。 
4. 对于每个传出边缘，计算穿过该边缘后的时间。 如果该值超过`k`，此移动是不可能的，因为旅行者需要在雨中继续太长时间。 
5. 如果边的目的地是避难所，则将新值替换为零。 到达避难所就完全消除了之前的连续行驶时间。 
6. 如果新值提高了邻居存储的值，则更新它并将邻居推入优先级队列。 如果最终到达目标顶点，则答案是可能的。 

为什么它有效：

 不变的是`dist[v]`始终存储到达所需的最佳剩余降雨时间`v`从一开始。 任何到达具有较大值的顶点的路线永远不会比到达具有较小值的顶点的路线更有用，因为每个未来的边都会增加相同的量，而避难所会消除累积的值。 优先级队列按照该值的升序处理状态，因此每次松弛都会首先考虑最有希望的部分路线。 由于每个转换都遵循降雨限制，并且每个有效转换都可用于搜索，因此算法在存在路径时准确地找到路径。 

# Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, m, k = map(int, input().split())
        a, b = map(int, input().split())

        s = int(input())
        shelters = []
        if s:
            shelters = list(map(int, input().split()))

        is_shelter = [False] * (n + 1)
        for x in shelters:
            is_shelter[x] = True

        graph = [[] for _ in range(n + 1)]
        for _ in range(m):
            u, v, w = map(int, input().split())
            graph[u].append((v, w))
            graph[v].append((u, w))

        inf = 10**30
        dist = [inf] * (n + 1)
        dist[a] = 0

        pq = [(0, a)]

        while pq:
            cur, u = heapq.heappop(pq)
            if cur != dist[u]:
                continue

            if u == b:
                break

            for v, w in graph[u]:
                nxt = cur + w
                if nxt > k:
                    continue

                if is_shelter[v]:
                    nxt = 0

                if nxt < dist[v]:
                    dist[v] = nxt
                    heapq.heappush(pq, (nxt, v))

        ans.append("YES" if dist[b] != inf else "NO")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```庇护所数组将顶点的特殊属性转换为松弛期间的恒定时间查找。 如果没有它，每次边缘遍历都需要搜索庇护所列表。 

这`dist`数组存储连续旅行时间，而不是总路径长度。 这是主要的实现细节。 进入避难所时重置该值是正常 Dijkstra 框架解决问题的原因。 

条件`nxt > k`在重置之前进行检查。 旅行者无法神奇地使用已经无法跨越的边缘末端的避难所。 仅在成功到达该顶点后才应用重置。 

Python 整数不会溢出，但大边权重可以创建比正常 32 位范围大得多的值，因此该实现使用大整数哨兵来表示无穷大。

# 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O((n+m)log n)`| 每个成功的距离更新都会进入优先级队列，并且在遍历期间检查每个边。 |
 | 空间|`O(n+m)`| 图表、距离数组、避难所标记和优先级队列存储线性数据量。 |

 这些约束允许使用线性算图算法，因为总图大小仅为`2 * 10^5`。 该解决方案对每个测试用例执行一次遍历，并且不依赖于避难所的数量。

 # 边缘情况

 当路径长度大于`k`但包含避难所，该算法从不比较总距离。 例如：```
3 2 6
1 3
1
2
1 2 3
2 3 3
```顶点的状态`2`变为零，因为它是一个避难所。 顶点的最终状态`3`是`3`，所以目的地可达。 

当庇护所因到达已违反限制而无法使用时，算法会在应用重置之前拒绝该边缘。 在：```
4 3 4
1 4
1
3
1 2 3
2 3 3
3 4 3
```旅行者到达顶点`2`有雨时`3`。 边到顶点`3`需要`6`，超出了限制，因此避难所永远不可用。 

当没有避难所时，该算法的行为类似于带有上限的正常最短路径可行性检查。 仅当从起点到目的地的每个边序列都位于同一连续段内时，才会接受路线。 对于单边长度`7`和`k = 10`，目的地接收距离`7`并被接受。
