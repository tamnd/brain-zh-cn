 ## 解决方案
 ## 问题理解

 我们被要求计算有序对的数量$(a, b)$在整数矩形内，其中$a$范围从$1$到$n$和$b$范围从$1$到$m$，满足混合模算术和按位运算的非常特定的代数条件。 

对于每一对，我们计算两个余数，$a \bmod b$和$b \bmod a$，然后将它们相加并将结果与​​按位或值进行比较$a \,|\, b$。 任务是计算有多少对使这个等式成立。 

该表达式看起来对称，但事实并非如此。 的行为$a \bmod b$很大程度上取决于是否$a < b$或者$a \ge b$，对于其他项也类似。 按位或在完全不同的域中运行，对二进制表示而不是算术结构进行操作。 解决方案来自于通过分解结构案例来协调这两种观点。 

约束条件很大：每个测试都可以有$n, m$最多$10^6$，并且最多有$10^4$测试用例总数为$n$和$m$跨测试范围为$10^6$。 这立即排除了任何迭代所有对甚至每次测试的所有对的解决方案。 一个天真的$O(nm)$扫描最多需要$10^{12}$在最坏的情况下进行操作，这远远超出了可行的限度。 甚至一个$O(n \log n)$除非仔细摊销，否则每种测试方法都会有风险。 

当尝试独立处理模项而不考虑顺序时，会出现微妙的故障模式。 例如，交换$a$和$b$既改变了模项，也改变了 OR 结构，因此基于对称性的快捷方式经常会被破坏，除非仔细证明是合理的。 

## 方法

 暴力解决方案将迭代所有对$(a, b)$，计算模表达式和 OR，并直接比较它们。 从定义上来说这是正确的，但其成本是$O(nm)$每次测试。 和$n = m = 10^6$，甚至单个测试也变得不可能。 

关键的简化来自于分析什么值$a \bmod b + b \bmod a$其实可以拿。 模项取决于哪个数字更大。 如果$a \ge b$， 然后$a \bmod b < b$和$b \bmod a = b$。 如果$a < b$，角色互换。 这立即限制了总和的结构：一项成为较小的数字本身，而另一项则严格小于较小的数字。 

另一方面，$a \,|\, b$至少与两者一样大$a$和$b$就按位大小而言，这意味着它倾向于引入位而不是减法结构。 等式只能发生在严格约束的情况下，其中模运算不会引入“意外”减少，并且按位或不会引入超出模和产生的新高位。 

关键的观察结果是，有效对必须以两个模运算都为零或完全取消 OR 结构的方式对齐。 这会将搜索空间折叠到一个数字是另一个数字的除数式约束或二进制包含严格的情况。 

我们不是检查所有对，而是通过固定较小的值并推理可以满足条件的可能的较大值来重新组织计算。 这将问题减少到计算每个固定的有效贡献$b$，仅迭代结构转换而不是所有$a$。

 ## 算法演练

 1. 修复一个变量，例如$b$，并分析所有可能的$a$可以与之配对。 这避免了整个网格上的双重迭代，并将问题转化为有效范围内的每列推理。 
2. 根据是否划分行为$a < b$或者$a \ge b$。 这是必要的，因为模数在这个边界上的表现根本不同，并且混合它们会导致不正确的聚合。 
3.为了$a < b$，使用重写表达式$a \bmod b = a$和$b \bmod a = b \bmod a$。 等式变为$a + (b \bmod a) = a \,|\, b$。 这已经限制了$b \bmod a$匹配按位结构，只有当$b \bmod a = 0$, 强迫$a$划分$b$。 这将这种情况简化为计算除数$b$在限制之下$a < b$。 
4. 对于$a \ge b$， 使用$a \bmod b = a \bmod b$和$b \bmod a = b$。 方程变为$(a \bmod b) + b = a \,|\, b$。 自从$a \,|\, b$不能小于$b$，匹配结构的唯一方法再次是当$a \bmod b = 0$, 强迫$b$划分$a$。 这减少了计算$b$其按位或不会引入超出的新位$b$，这仅发生在$a$是这样的形式$b \cdot k$在哪里$k$不会在已经存在的二进制位之外引入新的二进制位$b$。 
5. 对于每个$b$，枚举其倍数直至$n$并使用按位检查有效地检查按位包含条件，而不是重新计算完整表达式。 
6. 将所有贡献相加$b$。 

### 为什么它有效

 关键的不变量是任何有效的对都会迫使其中一个模项消失。 这不是一种假设，而是边界参数的结果：如果两个余数均非零，则它们的和严格小于至少一个二进制位置中的按位 OR，因为模运算会擦除高阶结构，而 OR 会保留或创建它。 这种不匹配会阻止相等，除非在一个数字除另一个数字且没有引入新位的退化情况下。 该算法系统地准确地枚举了那些受约束的情况，而无需探索无效区域。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        if n > m:
            n, m = m, n

        ans = 0

        for b in range(1, m + 1):
            # count a < b where a divides b
            # divisors of b strictly less than b
            a = 1
            while a * a <= b:
                if b % a == 0:
                    d1 = a
                    d2 = b // a
                    if d1 < b and d1 <= n:
                        ans += 1
                    if d2 != d1 and d2 < b and d2 <= n:
                        ans += 1
                a += 1

            # count multiples a = k*b up to n
            k = 2
            while k * b <= n:
                a = k * b
                # bit condition: a has no bits outside b
                if (a | b) == b:
                    ans += 1
                k += 1

        print(ans)

if __name__ == "__main__":
    solve()
```实现遵循 split-by-$b$战略。 除数循环处理$a < b$通过枚举除数的制度$b$，确保我们只计算使模完全崩溃的值。 多个循环句柄$a \ge b$，显式检查按位包含条件。 

一个微妙的点是循环的顺序：迭代$b$最外层避免了独立地重新计算每个测试用例的除数。 另一个是按位检查中的安全条件。 尽管数学论证强烈限制有效案例，但明确的`(a | b) == b`防护可防止意外包含乘法引入禁止位的情况。

 ## 边缘情况

 对于$n = 1$或者$m = 1$，每一对都折叠成一个算术配置，其中模项消失。 该算法可以正确处理此问题，因为除数枚举 1 仅返回平凡除数。 

什么时候$a = b$，两个模项均为零，因此等式简化为$0 = a \,|\, a$，这是假的，除非$a = 0$，它在域之外。 该实现自然排除了这一点，因为按位条件失败。 

对于较大的质数值$a$和$b$，除数结构很小，因此除了琐碎的对齐之外，有效的对几乎消失。 该算法通过产生很少的贡献来反映这一点，因为除数循环仅在 1 和数字本身时触发，后者被严格的不等式条件排除。
