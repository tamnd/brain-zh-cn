 ## 解决方案
 ## 问题理解

 该游戏是在整数数组上进行的。 一次有效的移动会移除一整块相等的值。 块意味着最大的连续组，其中每个元素都是相同的，因此玩家无法删除块的一部分。 爱丽丝先移动，但在游戏开始之前，她可以按照自己的意愿重新排列数组。 任务是确定 Alice 是否可以排列这些值，以便她有对抗 Bob 的获胜策略。 

输入描述了几个数组。 对于每个数组，输出是 Alice 选择最佳可能排序后最佳游戏下的获胜者。 我们只需要打印 Alice 或 Bob 是否获胜。 

重要的观察是爱丽丝控制了初始排列，因此原始位置并不重要。 只有多重值集才重要。 一旦值被分组，每个不同的值恰好贡献一个可移动的块，因为 Alice 可以将相等的值放在一起。 然后，游戏就变成了一个关于存在多少块以及玩家如何与移除它们进行交互的问题。 

约束足够大，模拟游戏是不现实的。 当元素总数达到 200000 左右时，任何尝试每种排列、每种分组或每种移动序列的方法都会爆炸。 解决方案必须以线性时间或接近线性时间处理数组。 

主要的边缘情况来自具有相同频率的值。 粗心的解决方案可能会计算不同的值，并假设移动次数始终是该计数，但块大小的奇偶性会改变结果。 

例如，考虑：```
1
3
5 5 5
```爱丽丝可以将其安排为`[5,5,5]`。 只有一个区块，所以爱丽丝将其删除并获胜。 输出是：```
Alice
```将每次出现视为独立移动的解决方案会错误地认为存在三个移动。 

另一个案例：```
1
4
1 1 2 2
```Alice 可以将数组排列为`[1,1,2,2]`。 有两个区块，爱丽丝先移除一个区块。 鲍勃删除了剩余的区块，因此爱丽丝输了。 输出是：```
Bob
```一个常见的错误是认为爱丽丝总是从对相等值进行分组中受益，但分组仅决定了块的数量。 玩家仍然交替移除这些方块。 

## 方法

 第一个想法是直接模拟游戏。 由于爱丽丝可以对数组重新排序，因此我们可以尝试不同的排列并在每一种排列上玩游戏。 这显然是不可能的，因为可能的排列数量增长得非常快。 

一个更好的蛮力想法是注意到只有等值组的长度才重要。 我们可以列举将频率分成连续块并计算获胜者的可能方法。 这也会失败，因为一个频率可以被分割成多种可能性，而分区总数太大。 

关键的观察结果是，Alice 总是可以将每次出现的相同值放在一起。 将一个值分成几个组从来没有用，因为它给了鲍勃额外的移动。 对于出现的值`cnt`次，最好的安排给出一个包含所有内容的块`cnt`副本。 

现在游戏被简化为块的集合。 每个不同的数字创建一个块。 玩家只需轮流删除方块即可。 由于每次移动都会删除一个方块，因此最后移动的玩家获胜。 

这意味着唯一重要的是最佳分组后不同值的数量。 如果块数为奇数，则爱丽丝将采取最后一步。 如果有偶数个块，鲍勃就会这样做。 

整个问题变成了计算数组中出现了多少个不同的值。

 ## 算法演练

 1. 读取数组并存储出现的每个值。 

原来的顺序是无关紧要的，因为爱丽丝可以在游戏开始之前重新排列所有内容。 
2. 计算唯一值的数量。 

通过将所有相等的值放在一起，可以将每个唯一值恰好变成一个最大块。 
3. 检查唯一值数量的奇偶性。 

如果计数为奇数，则爱丽丝移除最后剩余的块并获胜。 如果计数为偶数，则鲍勃获得最后一步并获胜。 

### 为什么它有效

 Alice重新排列数组后，所有相等的值可以连续放置。 这会为每个不同的值创建一个块。 使用相同的值创建多个方块只会增加移动次数，并且永远无法帮助爱丽丝，因为两个玩家每回合都会删除一个方块。 

因此，该游戏与正常的交替消除游戏相同，每个不同值一个对象。 当物体的数量为奇数时，爱丽丝就赢了，因为她开始并采取每一个奇数的动作。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        seen = set(a)

        if len(seen) % 2 == 1:
            ans.append("Alice")
        else:
            ans.append("Bob")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```使用该集合是因为​​它仅存储不同的值。 该集合的大小是 Alice 重新排列后可以创建的块的数量。 

输入大小可能很大，因此解决方案使用`sys.stdin.readline`并在打印前收集输出一次。 Python 整数在这里不会溢出，因为我们只存储值和计数。 

唯一微妙的一点是避免对原始位置的任何依赖。 对数组进行排序或检查相邻元素会解决不同的问题，因为爱丽丝在游戏开始之前改变了排列。
