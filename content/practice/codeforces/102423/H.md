 ## 解决方案
 ## 问题理解

 我们得到一个由不同小写字母组成的有限字母表（已按字母顺序编写）和一个其字符都属于该字母表的查询字符串。 我们需要构造每个与查询字符串的编辑距离恰好为 1 的不同字符串。 

距离为 1 意味着一次基本编辑就足够了。 我们可以在任意位置插入一个字母字符，删除一个现有字符，或者用不同的字母字符替换一个字符。 原始字符串本身不得被打印，因为它与自身的距离为零。 生成的字符串必须按字典顺序打印，并删除重复项。 

查询字符串的长度在 2 到 100 之间。字母表仅包含不同的小写字母，因此最多有 26 个字符。 这些界限很小。 即使我们独立生成每一个可能的编辑，也只有几千个候选。 对所有候选者使用二次算法是不必要的，但即使候选者数量本身也足够小，直接构造是自然的解决方案。 

主要的边缘情况来自重复生成。 例如，使用输入```
a
aa
```正确的输出是```
aaa
a
```插入`a`在第一个字符之前、两个字符之间或在第二个字符之后总是产生`aaa`，因此单独打印每个操作的粗心实现会输出相同的字符串三次。 删除任一出现的`a`产生相同的字符串`a`，创建另一个副本。 

第二种情况是替代。 和```
ab
aa
```更换任一`a`经过`b`产生`ba`，同时替换第二个字符也会产生`ab`。 更一般地，不同的编辑位置可能会导致相同的结果字符串，因此重复数据删除必须在生成候选之后进行，而不是仅基于所使用的操作。 

字母表也可以包含单个字符。 例如，```
a
aa
```根本没有可能的替代，因为没有可用的不同字符。 插入和删除仍然要考虑。 假设每个位置都有替换的实现将生成原始字符串或访问不存在的替代字符。 

## 方法

 最直接的方法是枚举每个合法编辑并将结果字符串放入集合中。 对于 (n+1) 个插入位置中的每一个，我们都会尝试 (k) 个字母字符中的每一个。 对于每个 (n) 个位置，我们生成通过删除该字符获得的字符串。 最后，对于每个位置，我们尝试与当前字母字符不同的每个字母字符，给出 (n(k-1)) 个替换候选。 

因此，生成的候选数为

 [
 (n+1)k+n+n(k-1)=2nk+k。 
]

 在最大值 (n=100) 和 (k=26) 下，这只是

 [
 2\cdot100\cdot26+26=5226
 ]

 候选人。 每个候选者的长度最多为 101，因此构建所有候选者只需要几十万个字符操作。 

简单的实现可以将所有候选生成到一个列表中，然后重复比较字符串以删除重复项。 这是正确的，因为明确考虑了每个可能的距离一操作，但是通过成对比较来去除重复可以采用 (O(C^2 n))，其中 (C) 是生成的候选者的数量。 (C) 大约为 5000，这已经是数百万次字符串比较，而且成本不必要。 

关键的观察是该问题并不要求我们计算操作数。 它要求唯一的结果字符串。 哈希集正是满足该要求所需的数据结构。 我们可以生成每个合法结果一次，将其插入到一个集合中，然后让散列自动折叠所有重复项。 生成后，将集合转换为列表并对其进行排序，给出所需的字典顺序。 

因此，蛮力思想仍然是解决方案的基础。 改进并不是要避免枚举编辑，因为编辑太少，无法证明更复杂的事情是合理的。 改进之处在于以有效执行重复数据删除的方式表示答案集合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解与成对重复删除 | (O(C^2 n + C\log C)) | (O(C^2 n + C\log C)) | (O(Cn)) | 正确但不必要的慢 |
 | 使用哈希集生成和删除重复 | (O(nk\cdot n + C\log C)) | (O(Cn)) | 已接受 |

 这里 (C=2nk+k)，以及 (n\le100) 和 (k\le26)，两个界限都很小。 

## 算法演练

 1. 读取字母表和查询字符串。 令 (n) 为查询长度，(k) 为字母表大小。 每个插入或替换的字符都必须来自该字母表，因此这两个字符串完整地描述了可用的编辑。 
2. 创建一个空集，名为`answers`。 使用集合是因为​​不同的编辑可以产生完全相同的字符串，并且所需的输出仅包含每个字符串一次。 
3. 对于每个位置`0`通过`n`，在该位置插入每个字母字符。 长度为 (n) 的字符串中有 (n+1) 个间隙，包括第一个字符之前的间隙和最后一个字符之后的间隙。 
4. 对于每个字符位置，删除该字符并将结果字符串插入到集合中。 每次删除都会花费一成本，因此这些正是所有可能的删除结果。 
5. 对于每个字符位置，尝试除当前字符之外的每个字母字符，并用它替换该字符。 跳过当前字符是必要的，因为替换字符本身不会执行编辑，并且会错误地引入原始查询字符串。 
6. 将集合转换为列表并按字典顺序排序。 字母表本身已经排序，但生成的字符串具有不同的长度和编辑位置，因此无法从生成顺序可靠地获得它们的最终顺序。 
7. 将排序列表中的每个字符串打印在其自己的行上。 如果两个编辑序列产生相同的字符串，则该集合已经删除了重复的字符串。 

### 为什么它有效

 每个距离正好为 1 的字符串必须可以通过以下三种操作之一获得：一次插入、一次删除或一次替换。 该算法显式枚举所有三个操作的每个合法实例，因此不会错过任何有效答案。 

插入循环考虑每个可能的位置和每个字母字符。 删除循环考虑每个现有字符。 替换循环考虑每个位置和每个不同的字母字符。 因此，每一种可能的一次性编辑转换都会出现在生成的候选者中。 

该集合仅删除相同的字符串，而不删除不同的字符串。 由于原始字符串永远不会通过有效的插入或删除生成，并且替换故意排除当前字符，因此每个剩余元素的距离恰好为 1。 然后排序仅更改表示顺序，因此最终输出正是所需的按字典顺序排列的字符串集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve(data: str) -> str:
    lines = data.splitlines()
    alphabet = lines[0].strip()
    s = lines[1].strip()

    n = len(s)
    answers = set()

    # Insert one alphabet character at every possible position.
    for i in range(n + 1):
        left = s[:i]
        right = s[i:]
        for ch in alphabet:
            answers.add(left + ch + right)

    # Delete one character.
    for i in range(n):
        answers.add(s[:i] + s[i + 1:])

    # Replace one character by a different alphabet character.
    for i in range(n):
        for ch in alphabet:
            if ch != s[i]:
                answers.add(s[:i] + ch + s[i + 1:])

    return "\n".join(sorted(answers))

def main():
    data = sys.stdin.read()
    sys.stdout.write(solve(data))

if __name__ == "__main__":
    main()
```前两行输入被读取为字母表和查询字符串。 没有测试用例计数，因此可以立即消耗整个输入。 

插入循环使用`range(n + 1)`因为长度为 (n) 的字符串有 (n+1) 个插入间隙。 表达式`s[:i] + ch + s[i:]`插入物`ch`不修改原始字符串。 

删除表达式`s[:i] + s[i + 1:]`精确删除位置处的字符`i`。 它还自然地处理第一个和最后一个位置，这是切片错误的常见来源。 

对于替换，条件`ch != s[i]`是必不可少的。 如果没有它，原始查询字符串将被插入到`answers`，即使它与自身的编辑距离为零。 

Python 字符串是不可变的，因此每次操作都会创建一个新字符串。 这在这里是完全足够的，因为最多生成 5226 个候选，每个候选的长度最多为 101。Python 整数与计算无关，因此不存在溢出问题。 

决赛`sorted(answers)`给出了普通的字典字符串排序，这正是问题所需要的。

 ## 边缘情况

 对于单字符字母表，请考虑```
a
aa
```没有合法的替代品，因为`a`是唯一可用的角色。 插入`a`在三个间隙中的任何一个都会产生`aaa`，同时删除任一出现都会产生`a`。 该集合将这三个插入结果和两个删除结果减少为两个字符串，给出```
a
aaa
```该算法处理这个问题是因为替换循环根本没有满足的字符`ch != s[i]`。 

对于重复的字符，请考虑```
ab
aaa
```插入`a`在四个位置中的任何一个都会产生`aaaa`，同时删除三个位置中的任何一个都会产生`aa`。 将每个操作直接附加到输出的简单实现会多次打印这些字符串。 该集合将每个结果存储一次，因此最终输出仅包含唯一的字符串。 

对于第一个和最后一个插入位置，考虑```
ab
ab
```位置`0`插入会产生诸如以下的字符串`aab`和`bab`，同时位置`2`产生`aba`和`abb`。 循环使用`range(n + 1)`，因此两个边界间隙都包括在内。 仅使用`range(n)`会默默地错过最后的所有插入。 

对于替换，相同的输入说明了为什么必须排除当前字符。 在零位置，替换`a`经过`a`会重现`ab`，但该操作不会改变任何内容并且距离为零。 条件`ch != s[i]`防止原始查询字符串进入答案集。 

对于删除，两个字符的字符串```
ab
ab
```有删除结果`b`和`a`。 切片表达式正确处理两个端点，因为`s[:0] + s[1:]`删除第一个字符并`s[:1] + s[2:]`删除第二个。 

最后，重复输出不限于重复的字符。 当周围的字符匹配时，在相邻位置插入相同的字符也可以收敛到相同的最终字符串。 这就是为什么必须对实际结果字符串而不是操作描述执行重复数据删除。 哈希集正是给出了这种行为。
