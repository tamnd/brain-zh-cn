 ## 解决方案
 ## 问题理解

 我们有一个由 (n) 个整数组成的序列 (X)。 每个元素都位于 (1) 和 (k) 之间，并且从 (1) 到 (k) 的每个值都出现在序列中的某个位置。 我们需要删除一些元素，同时保留剩余所有元素的相对顺序。 

最终序列必须包含每个值恰好一次，因此其长度恰好为 (k)。 在所有这些子序列中，我们想要字典顺序最小的一个。 换句话说，我们首先最小化第一个选择的值，然后在具有相同第一个值的选项中最小化第二个选择的值，依此类推。 原始问题给出 (n) 最多 (2\cdot10^5)，因此重复扫描序列的大部分或考虑许多可能的子序列的解决方案是不可行的。 

线性或 (O(n\log n)) 解是自然的目标。 对于 (2\cdot10^5) 个元素和两秒的限制，(O(n^2)) 在最坏的情况下意味着大约 (4\cdot10^{10}) 次基本迭代，远远超出了竞争性编程实现可以处理的范围。 这个问题的结构是有利的，因为我们只需要每个值出现一次，并且只要稍后的出现给我们提供了更好的词典选择，重复的出现就可以被丢弃。 

第一个边缘情况是 (k=1) 时，因此整个答案由单个值组成。 例如，```
1 1
1
```有输出```
1
```假设必须存在涉及前一个元素的堆栈操作的粗心实现可能会在这里失败，因为根本不存在前一个元素。 

另一种边缘情况是当序列已经是排列时。 例如，```
5 5
1
2
3
4
5
```有输出```
1 2 3 4 5
```每个值都必须保留，因为正好有 (k) 个元素。 仅仅因为当前值较小而删除堆栈元素的实现可能会意外删除以后不再出现的值。 

接近尾声的重复是另一个常见的错误来源。 考虑```
6 3
3
2
1
3
1
3
```答案是```
2 1 3
```第一个`3`不能成为最佳答案的一部分，因为选择`2`next 给出较小的第一个元素，后面的元素`3`仍然可用。 然而，最终`3`必须保留，因为选择后`2`和`1`，不晚了`3`存在。 贪婪堆栈必须区分可以安全删除的元素和删除后会使剩余序列不完整的元素。 

## 方法

 一种直接的暴力方法是枚举可能的子序列，保留包含从 (1) 到 (k) 的每个值的子序列恰好一次，然后选择字典顺序最小的子序列。 这是正确的，因为每个有效答案都被明确考虑。 问题是子序列的数量。 总共有 (2^n) 个子序列，当 (k) 在 (n/2) 左右时，恰好长度 (k) 的候选数为

 [
 \binom{n}{\lfloor n/2\rfloor},
 ]

 大约为 (2^n/\sqrt{n})。 对于(n=2\cdot10^5)，这是完全不可行的。 

一种不太极端的暴力策略是从左到右构建答案。 在每个位置，按升序尝试候选值，并搜索仍使每个缺失值可用的出现情况。 即使仔细执行每个可行性检查，重复扫描后缀也可能需要 (O(nk)) 的工作。 在最坏的情况下，这会达到大约 (4\cdot10^{10}) 次操作。 

有用的观察是，字典最小化给了我们一个非常具体的理由来删除已经选择的值。 假设当前答案以值 (a) 结束，下一个序列值为 (b<a)。 如果 (a) 稍后再次发生，则保持当前 (a) 永远不是最佳选择。 用较小的 (b) 替换它会使答案按字典顺序更小，而稍后出现的 (a) 仍然可以提供所需的副本。 

这给出了单调堆栈策略。 我们从左到右处理序列。 该堆栈代表了我们当前可以构建的最佳前缀。 当较小的值到达时，我们会从堆栈末尾删除较大的值，只要这些值稍后再次出现即可。 如果某个值稍后没有出现，则该值将被锁定并且无法删除。 

还有一个条件。 我们只需要每个值一次，因此如果当前值已经在堆栈中，我们只需跳过它。 第一个出现的值不一定是我们想要的，但暂时保留它可以让堆栈规则稍后在最后一个可能出现的值之前出现较小的值时替换它。 

因此，关键数据结构只是一个`last`数组存储每个值的最终位置。 在扫描期间，堆栈不包含重复项，并且每次弹出都会因稍后出现的另一个事件的存在而被证明是合理的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(2^n)) 个候选人 | (O(n)) | (O(n)) | 太慢了 |
 | 重复贪婪扫描| (O(nk)) | (O(nk)) | (O(k)) | 太慢了 |
 | 单调堆栈 | (O(n)) | (O(n)) | (O(n+k)) | 已接受 |

 ## 算法演练

 1.读取序列并计算`last[x]`，每个值 (x) 出现的最终索引。 我们需要此信息，因为只有当保证另一个副本稍后仍然可用时，才能从当前答案中删除值。 
2.维护一个包含当前最佳子序列前缀的堆栈，并维护一个布尔数组`used`告诉我们哪些值已经在堆栈中。 堆栈永远不会两次包含相同的值，这直接满足最终答案仅包含每个值一次的要求。 
3. 从左到右处理每个值 (x)。 如果`used[x]`已经为真，跳过 (x)。 保留另一个副本将违反一次性条件，并且该副本无法改进答案，因为现有的出现已经在堆栈中表示。 
4. 如果未使用 (x)，则将其与堆栈中的最后一个值进行比较。 当堆栈非空时，其最后一个值大于 (x)，并且最后一个值在当前位置之后再次出现，将其弹出并标记为未使用。 new (x) 较小，因此将其放在前面会使序列按字典顺序更小，而弹出值的较晚出现则保留了可行性。 
5. 一旦栈顶小于(x)，或者栈顶值不再出现，就停止出栈。 在第一种情况下，替换它会使序列更大。 在第二种情况下，删除它会丢失该值的唯一剩余副本。 
6. 将 (x) 推入堆栈并将其标记为已使用。 继续，直到处理完每个输入元素。 
7. 打印堆栈。 因为从 (1) 到 (k) 的每个值都保证出现在输入中，并且我们仅在剩余另一个副本时删除一个值，所以最终堆栈只包含所有 (k) 个值一次。 

### 为什么它有效

 关键的不变量是，在处理输入的任何前缀之后，堆栈是字典顺序上最小的不同值子序列，它仍然可以扩展以包含尚未永久丢失的每个值。 

当新值 (x) 小于堆栈顶部 (y) 时，将 (y) 保留在 (x) 之前会使结果按字典顺序变得更差。 我们可以在稍后发生另一个副本时准确地删除 (y)，因此删除它不会导致有效的完成变得不可能。 重复此过程将删除每个大于 (x) 且可替换的堆栈后缀。 

如果堆栈值后来不再出现，则无法将其删除，因为它会在每次可能的完成中消失。 如果栈顶小于 (x)，则首先保留较小的值在字典顺序上已经是最佳的。 因此，每次压入或弹出都是由字典最优性和可行性强制的，这证明最终的堆栈是所需的子序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = [int(input()) for _ in range(n)]

    last = [0] * (k + 1)

    for i, x in enumerate(a):
        last[x] = i

    used = [False] * (k + 1)
    stack = []

    for i, x in enumerate(a):
        if used[x]:
            continue

        while stack:
            top = stack[-1]

            if top <= x:
                break

            if last[top] <= i:
                break

            stack.pop()
            used[top] = False

        stack.append(x)
        used[x] = True

    print(*stack)

if __name__ == "__main__":
    solve()
```第一个循环计算每个值的最后一次出现。 由于索引是从左到右处理的，因此分配`last[x] = i`自然地留下数组中的最后一个出现。 

这`used`数组可防止重复输入答案。 这与`last`:`last`回答是否可以删除某个值，而`used`回答我们是否已经在当前答案中拥有该值的副本。 

内部`while`循环是单调堆栈操作。 条件`top > x`是字典顺序条件。 条件`last[top] > i`是可行性条件。 两者都是必需的。 省略第二个条件可以删除唯一剩余的值出现。 

比较使用`last[top] <= i`而不是`last[top] < i`因为当前索引不能是以后出现的`top`什么时候`top`已经在堆栈中，但是使用`<=`使边界明确且安全。 实际上，对于与当前不同的堆栈值`x`,`last[top]`总是至少`i + 1`如果仍然可用。 

每个值在删除之间最多推送一次，并且每次推送最多弹出一次。 更准确地说，每次出现只会导致恒定的摊销堆栈工作，因此整个算法是线性的。 

Python 整数在这里不会引入任何溢出问题，因为该算法仅操作以 (2\cdot10^5) 为界的索引和值。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| --- | ---|
 | 时间 | (O(n+k)) | 计算最后出现的次数需要 (O(n))，并且每次堆栈压入或弹出都会分摊 (O(1)) |
 | 空间| (O(n+k)) | 序列、堆栈、`last`， 和`used`数组占据线性空间 |

 对于 (n\le2\cdot10^5)，算法仅对每个输入元素执行恒定量的摊销工作。 这完全在两秒限制的预期范围内，而二次替代方案将需要数百亿次运算。

 ## 边缘情况

 当只有一个不同的值时，例如```
1 1
1
```该算法从一个空堆栈开始，压入`1`，并立即完成。 没有pop执行，结果是`1`。 相同的逻辑可以处理任意多个重复项，因为以后的每个重复项`1`看到`used[1] == True`并被跳过。 

当每个值都只出现一次时，请考虑```
5 5
1
2
3
4
5
```堆栈增长到`[1, 2, 3, 4, 5]`。 每当有新值到达时，栈顶就会变小，因此不可能弹出。 输出保持原始序列。 这是必要的，因为删除任何值都将导致无法包含其中的每个数字`1`通过`5`。 

最微妙的边界情况发生在较小的值在已到达最终出现的值之后到达时。 为了```
4 3
3
2
1
3
```第一个`3`被删除时`2`到达是因为另一个`3`存在于索引 3 处。堆栈变为`[2]`。 什么时候`1`到达，`2`以后不会出现，因此无法删除。 决赛`3`然后添加，产生```
2 1 3
```这正是检查的条件`last[top] > i`。 

选择后出现的重复值也必须被忽略。 在```
6 3
3
2
1
3
1
3
```第一个`3`被替换为`2`， 这`2`被保留是因为它没有后来的副本，并且后来的副本`3`最终被选中。 随后的`1`和`3`被跳过，因为两个值都已表示。 结果是`2 1 3`。 

最大尺寸的情况不需要不同的算法处理。 对于 (n=200000) 和 (k=1)，每个输入值是`1`，因此第一个元素被推送，所有剩余元素被跳过。 该算法仍然只执行 (O(n)) 工作，这正是最后出现堆栈公式扩展到完全约束的原因。
