 ## 解决方案
 ## 问题理解

 地球周围有 (N) 颗恒星。 对于每颗恒星 (i)，三个值描述了它对宇宙飞船旅行距离的贡献。 理想情况下，恒星与方向 (a_i) 对齐，给出最大贡献 (T_i)，并且对于发射方向远离 (a_i) 的每弧度，损失 (s_i) 单位的行进距离。 角距离是圆形的，因此稍微移动超过角度 (0) 相当于稍微移动到 (2\pi) 之前。 

如果选择的发射方向是（x），则星号（i）贡献

 [
 f_i(x)=\max(0,T_i-s_i\operatorname{dist}(a_i,x))。 
]

 总距离是所有这些贡献的总和，我们需要它在一整圈旋转中的最大值。 输入最多包含 (10^5) 个星，实值参数小数点后最多有六位数字。 所需的数值误差为(10^{-6})。 

界限 (N\le 10^5) 立即排除尝试许多候选方向并评估每个方向的所有星星。 即使我们只考虑每颗恒星的三个特殊方向，这也已经意味着在最坏情况下的评估约为 (3N^2)，约为 (3\cdot10^{10})。 围绕 (O(N\log N)) 的解决方案是合适的，因为对数十万个事件进行排序主导了工作，并且很容易满足五秒竞赛限制。 

直接实现可能会错误处理几种边缘情况。 如果 (s_i=0)，则恒星对每个方向都贡献 (T_i)。 例如，```
1
5 0 1
```有答案```
5.000000
```一个粗心的实现总是计算 (T_i/s_i) 除以零。 

第二个问题是圆形边界。 考虑```
2
1 1 0
1 1 6.183185
```第二个角度接近 (2\pi-0.1)，因此两个有用区域在 (0/2\pi) 边界上重叠。 最大值约为```
1.900000
```将角度间隔视为普通间隔并且不将其包裹的实现将错过这种重叠。 

第三种特殊情况发生在一颗恒星至少保持半圆活跃状态时。 例如，```
2
10 1 0
10 1 3.141593
```有大约答案```
16.858407
```半径 (T_i/s_i) 大于 (\pi)，因此围绕圆的贡献永远不会达到零。 将其活动区域视为半径为 (T_i/s_i) 的普通三角形会错误地延伸到圆形距离改变方向的点之外。 

最后，几颗星星可以具有完全相同的首选角度。 例如，```
3
5 1 1
5 1 1
5 1 1
```有答案```
15.000000
```所有导数变化都发生在相同的坐标处。 独立处理事件很好，但实现不能假设每个事件坐标都是唯一的。 

## 方法

 直接的方法是确定候选方向并评估每个方向的总贡献。 每颗恒星的贡献会在其首选方向和其贡献变为零的两个方向上改变公式。 这给出了 (O(N)) 个候选方向。 独立评估每个候选人的总贡献需要 (O(N)) 工作，需要 (O(N^2)) 时间。 对于 (N=10^5)，最坏的情况大约是 (10^{10}) 颗星评估，这远远超出了五秒的限制。 

蛮力之所以有效，是因为每个个体的贡献都是分段线性的。 失败来自于从头开始反复重新计算总和。 

关键的观察结果是整个总和也是分段线性的。 在某些星形改变其斜率的两个连续点之间，每个星形都有固定的线性公式，因此总函数也有固定的斜率。 区间上的线性函数在端点之一达到最大值。 我们只需要知道随着角度旋转斜率如何变化。 

对于有用角半径为的恒星

 [
 d=\min\left(\pi,\frac{T_i}{s_i}\right),
 ]

 从 (a_i-d) 到 (a_i)，其贡献随着斜率 (+s_i) 上升，然后从 (a_i) 到 (a_i+d) 随着斜率 (-s_i) 下降。 因此导数变化为

 [
 +s_i,\quad -2s_i,\quad +s_i
 ]

 在这三个位置。 

唯一复杂的是 (0) 和 (2\pi) 处的圆形边界。 我们通过将包裹端点移回到区间 ([0,2\pi]) 并相应地调整初始导数来处理它。 这仅给出了每个非常数恒星的三个事件。 

由此产生的方法是对坡度变化事件的标准扫描。 我们首先计算角度 (0) 处的总值，紧随角度 (0) 之后计算全导数，对所有导数变化事件进行排序，然后对从一个事件到下一个事件的当前斜率进行积分。 

同样的分段线性事件思想也反映在该竞赛问题的公认解决方案中，该解决方案通过其左端点、峰值和右端点表示每个星星，并明确处理穿过 (0) 和 (2\pi) 的间隔。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(N^2)) | (O(N)) | 太慢了 |
 | 最佳| (O(N\log N)) | (O(N)) | 已接受 |

 ## 算法演练

 1. 对于每个 (s_i=0) 的星星，将 (T_i) 直接添加到当前值。 它的贡献永远不会改变，因此它不会产生衍生事件。 
2. 对于每隔一个恒星，计算

 [
 d_i=\min\left(\pi,\frac{T_i}{s_i}\right)。 
]

 (\pi) 的最小值可以正确处理圆形距离。 最短角距离不能超过 (\pi)，因此一旦 (T_i/s_i\ge\pi)，贡献在任何地方都保持正值，并且相关斜率变化发生在首选方向及其对映点。 

1. 计算该恒星在发射角 (0) 处的贡献并将其添加到运行值中。 从 (a_i) 到 (0) 的圆距离就是 (\min(a_i,2\pi-a_i))。 
2. 定义三个事件位置

 [
 l=a_i-d_i，\qquad m=a_i，\qquad r=a_i+d_i。 
]

 在 (l) 处，导数改变 (+s_i)。 在 (m) 处，导数变化 (-2s_i)。 在 (r) 处，它改变了 (+s_i)。 

1. 如果 (l<0)，则添加 (2\pi)，使事件位于扫描间隔内。 由于该区间与角度 (0) 相交，因此恒星在角度 (0) 之后就已经位于其上升侧，因此将 (s_i) 添加到初始导数中。 
2. 如果 (r>2\pi)，则从中减去 (2\pi)。 贡献值已经在角度 (0) 之后的下降侧，因此从初始导数中减去 (s_i)。 

严格的不平等很重要。 如果端点恰好是 (0) 或 (2\pi)，则它已经是边界处的事件，并且不代表包装间隔。

1. 按角度对所有事件进行排序。 在两个连续事件之间，没有星形改变斜率，因此总函数在那里是一条直线。 
2. 从角度 (0) 处的总值、初始导数和前一个角度 (0) 开始。 对于角度 (x) 处的每个事件，将值提前

 [
 \text{值} \mathrel{+}= \text{斜率}\cdot(x-\text{前一个角度})。 
]

 然后应用事件的导数变化并更新最佳值。 

1.返回遇到的最大值。 该函数是周期性的，角度 (2\pi) 与角度 (0) 方向相同，因此检查初始位置和每个导数变化位置覆盖整个圆。 

### 为什么它有效

 对于每颗恒星，将 (T_i/s_i) 替换为 (\min(\pi,T_i/s_i)) 后，其贡献在其左边界、首选角度和右边界之间的每个间隔上都是线性的。 因此，它的导数在这三个事件之间是恒定的。 

所有星星的总和在连续的全局事件之间也是线性的。 线性函数不能具有严格的内部最大值，因此全局最大值必须出现在角度 (0) 或事件坐标处。 扫描通过积分当前总斜率然后应用导数变化来保持每个此类坐标的精确函数值。 因此，扫描记录的最大值正是最大行进距离。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

PI = math.pi
TWO_PI = 2.0 * math.pi

def solve():
    n = int(input())

    events = []
    cur = 0.0
    initial_slope = 0.0

    for _ in range(n):
        t, s, a = map(float, input().split())

        if s == 0.0:
            cur += t
            continue

        # The angular contribution can never depend on a distance
        # larger than pi.
        d = min(PI, t / s)

        # Contribution at angle 0.
        dist0 = min(a, TWO_PI - a)
        cur += max(0.0, t - s * dist0)

        left = a - d
        right = a + d

        # If the active interval crosses 0, its rising segment
        # is already active immediately after angle 0.
        if left < 0.0:
            left += TWO_PI
            initial_slope += s

        # If the active interval crosses 2*pi, its falling segment
        # is already active immediately after angle 0.
        if right > TWO_PI:
            right -= TWO_PI
            initial_slope -= s

        events.append((left, s))
        events.append((a, -2.0 * s))
        events.append((right, s))

    if not events:
        print(f"{cur:.6f}")
        return

    events.sort()

    best = cur
    slope = initial_slope
    previous = 0.0

    for angle, delta in events:
        cur += slope * (angle - previous)
        best = max(best, cur)

        slope += delta
        previous = angle

    print(f"{best:.6f}")

if __name__ == "__main__":
    solve()
```输入循环在计算 (T_i/s_i) 之前分离 (s_i=0) 情况。 这样的恒星会贡献一个常数（T_i），因此为其存储任何事件只会浪费时间。 

对于非常星来说，`dist0 = min(a, TWO_PI - a)`计算其距方向 (0) 的最短角距离。 这会在扫描开始时初始化整个目标的精确值。 

三个事件条目对衍生变化进行编码。 左端点开始上升段，首选角度将导数从 (+s_i) 更改为 (-s_i)，右端点将其更改回零。 这就是增量为 (+s_i)、(-2s_i) 和 (+s_i) 的原因。 

环绕调整是微妙的部分。 如果左端点为负，则星形的上升段与角度 (0) 相交，因此初始导数已包含 (+s_i)。 如果右端点超过(2\pi)，则下降段越过边界，因此初始导数包括(-s_i)。 

扫描对导数进行积分，而不是重新计算目标。 表达式`cur += slope * (angle - previous)`正是线性函数在该区间内的值变化。 仅在到达事件坐标后才应用导数更改，这避免了断点本身出现离一式错误。 

蟒蛇的`float`这里就足够了。 输入最多有六位小数，所需的答案容差为 (10^{-6})。 最大总贡献最多为 (10^8)，仍然在普通双精度算术提供足够绝对精度的精度范围内。 原始语句指定相同的（10^{-6}）输出容差。

 ## 边缘情况

 当(s_i=0)时，恒星根本没有角衰变。 为了```
1
5 0 1
```贡献始终为 (5)。 该算法在计算 (T_i/s_i) 之前检测到这一点，将 (5) 直接添加到`cur`，并且不创建任何事件。 最终的答案是`5.000000`。 

当有效区间穿过角度边界时，左端点和右端点不能简单地保持为普通实数。 为了```
2
1 1 0
1 1 6.183185
```第二颗星在角度 (0) 之前和之后处于活动状态。 该算法将其位于间隔之外的端点向后移动 (2\pi)，并更改初始导数以考虑在角度 (0) 处已处于活动状态的部分。 扫描结果发现`1.900000`。 

当 (T_i/s_i\ge\pi) 时，围绕圆的贡献永远不会变为负值。 为了```
2
10 1 0
10 1 3.141593
```每一颗星星都在到处活跃。 该算法将有用半径限制为 (\pi)，因此其斜率以首选角度和相反角度变化，而不是发明更长的活动间隔。 所得的最大值大约为`16.858407`。 

当多个事件坐标重合时，可以按任何顺序应用它们的导数变化，因为从一个相等的坐标移动到下一个坐标会将角度更改为零。 为了```
3
5 1 1
5 1 1
5 1 1
```所有三个峰都以相同的角度出现。 扫描在该坐标处应用三个相同的导数变化并正确获得`15.000000`。 

最终的边界也是安全的。 角度 (2\pi) 处的目标与其在角度 (0) 处的值相同，后者已包含为初始候选值。 扫描只需要一个完整周期内的事件坐标，因此没有额外的端点可以包含未发现的最大值。
