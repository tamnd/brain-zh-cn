 ## 解决方案
 ## 问题理解

 该问题描述了一系列石堆，每堆石堆代表一种动物。 动物一开始有一定数量的石头。 然后，在每一轮中，有一个数字`k`已宣布。 当前大小可被整除的每个堆`k`会得分，所以艾玛立即在每一堆石头中添加一块石头。 添加的石头保留在那里，这意味着同一动物可以在以后的回合中再次改变。 

任务是计算艾玛必须扔的石头总数。 由于每堆都可以被当前整除`k`必须增加，没有涉及最优策略的选择。 我们只需要模拟强制的改变，但是我们需要这样做而不需要检查所有的`n`每轮的动物。 

输入最多包含`10^5`动物和`10^5`回合。 初始桩尺寸最多为`3 * 10^5`，并且每个宣布的除数也至多`3 * 10^5`。 直接一个`n * m`模拟可能需要`10^10`可分性检查，这远远超出了五秒时间限制所能支持的范围。 最大可能的堆尺寸最多为`3 * 10^5 + 10^5 = 4 * 10^5`，因为每轮单个堆最多可以增加一次。 这个相对较小的值范围是我们利用的结构属性。 

一个微妙的情况是当几只动物具有相同的桩尺寸时。 例如，```
3 3
2
2
2
2
3
4
```正确答案是`9`。 所有三堆都变成`3`在第一轮中，然后全部变成`4`在第二个，然后一切都变成`5`在第三个。 单独存储每只动物的模拟在这里进行九次单独更新，而这三种动物可以用一个频率来表示`3`。 

另一个重要的情况是，堆只能被后面的除数整除，因为它之前已经增加了。 例如，```
1 2
2
2
3
```第一个`2`将堆从`2`到`3`，以及后来的`3`将其更改为`3`到`4`。 答案是`2`。 仅根据初始值确定所有受影响动物的解决方案会错过第二次操作。 

第三种边界情况是一堆永远不能被任何公布的值整除的堆。 例如，```
1 2
1
2
3
```答案是`0`。 价值`1`不会仅仅因为它存在而改变，因为宣布的除数是`2`和`1`不能被整除`2`。 将“不是倍数”与“小于除数”混淆会给出错误的更新。 

## 方法

 简单的解决方案存储所有`n`通过检查每只动物来确定每一轮的堆大小和处理过程。 如果当前除数是`k`，我们测试是否`a[i] % k == 0`，有则加一，累加变化次数。 这是正确的，因为它完全遵循游戏规则，包括前几轮所做的更改。 

问题是成本。 可以有`10^5`动物和`10^5`回合，放弃`10^10`最坏情况下的求模运算。 即使使用非常便宜的整数运算，这也太大了。 

有用的观察结果是，当前桩尺寸相同的动物是完全可以互换的。 假设有`cnt[x]`目前持有的动物`x`石头。 如果`x`可以被当前整除`k`， 全部`cnt[x]`它们一起改变。 我们可以添加`cnt[x]`到答案并将整个频率从`x`到`x + 1`。 

还有一个问题：我们如何找到所有当前占用的可被整除的值`k`无需扫描全部`x`从`1`到`4 * 10^5`？ 

对于每个值`x`，我们知道它的所有约数。 我们为每个可能的已公布除数维护一个集合`k`。 设定为`k`恰好包含当前被占用并可整除的堆大小`k`。 然后，查询可以立即从该集合中获取相关的不同堆大小。 

当一个值`x`移动到`x + 1`，其成员资格仅针对除数发生变化`x`和`x + 1`。 我们删除`x`从与其旧值对应的除数集中并插入`x + 1`到与其新值相对应的除数集合中。 由于取值范围仅约为`4 * 10^5`，所有除数关系都可以用筛子预先计算。 

蛮力之所以有效，是因为它明确地检查了每只动物并应用了规则。 当对许多动物和回合重复相同的操作时，它会失败。 观察到相同的桩大小可以作为一组进行处理，这让我们可以用价值级别的模拟来代替动物级别的模拟，而除数集使每一轮仅访问可以实际改变的值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(nm)`|`O(n)`| 太慢了 |
 | 值频率 + 除数集 |`O(V log V + U · D · log V)`|`O(V log V)`| 已接受 |

 这里`V = 4 * 10^5`,`D`是某个值的相关除数的最大数量，并且`U`是实际处理的不同值转换的数量。 除数筛部分以小值域为界，而动态部分则处理不同的桩尺寸而不是单个动物。 

## 算法演练

 1. 阅读所有初始堆大小和所有宣布的除数。 在模拟之前，已公布的除数的完整序列是已知的，因此我们只需要维护实际可以查询的除数的集合。 
2. 使用以下方法计算当前每个堆大小有多少只动物`cnt[x]`。 必须对相同的桩大小进行分组，因为具有相同值的每只动物在以后的每一轮中都会表现相同。 
3. 预先计算每个除数`d >= 2`对于每种可能的桩尺寸。 筛子在这里很自然地起作用：对于每个`d`， 访问`d, 2d, 3d, ...`并记录`d`作为除数。 
4.对于每个占用的初始值`x`， 插入`x`进入属于每个除数的集合`x`出现在查询序列中。 这建立了一个不变量，即集合恰好包含可被其相关除数整除的占用值。 
5. 按顺序处理宣布的除数。 对于查询`k`，取当前存储在集合中的所有值`k`。 每个这样的值都可以被整除`k`，因此每只具有该价值的动物都必须获得一颗石头。 
6. 对于每个受影响的值`x`， 添加`cnt[x]`到答案。 然后传输完整的频率`x`到`x + 1`，因为所有动物在`x`在这一轮中恰好改变了一颗棋子。 
7. 删除`x`从与其旧值关联的除数集中，然后插入`x + 1`到与其新值关联的除数集中。 成员资格会发生变化，因为该堆物理上已从一个整数移动到下一个整数。 
8. 清除当前设置`k`回合结束后。 每个可以被整除的值`k`刚刚被增加，因此不再能被整除`k`，因此保留旧条目将使后续查询处理不存在的状态。 

### 为什么它有效

 中心不变量是`cnt[x]`是当前堆大小恰好为的动物数量`x`，对于每个查询的除数`k`，它的集合恰好包含占用的值`x`满意的`x % k == 0`。 

一开始，不变量成立，因为每个初始占用值都被插入到其除数的集合中。 在一轮比赛中，设定为`k`恰恰包含了动物必须改变的价值观。 移动`cnt[x]`从`x`到`x + 1`完全符合所有这些动物所需的操作。 去除`x`从旧的除数集合中插入`x + 1`到它的新除数集合中恢复下一轮的不变量。 因此，每一次强制添加的石子都只计算一次，并且不会计算不必要的添加。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXV = 400000

def solve():
    n, m = map(int, input().split())

    initial = [int(input()) for _ in range(n)]
    queries = [int(input()) for _ in range(m)]

    queried = [False] * (MAXV + 1)
    for k in queries:
        queried[k] = True

    # divisors[x] contains all divisors >= 2 of x.
    divisors = [[] for _ in range(MAXV + 1)]

    for d in range(2, MAXV + 1):
        for x in range(d, MAXV + 1, d):
            divisors[x].append(d)

    # cnt[x] = number of animals currently having x stones.
    cnt = [0] * (MAXV + 2)

    # Only queried divisors need sets.
    buckets = {}
    for k in set(queries):
        buckets[k] = set()

    for x in initial:
        cnt[x] += 1

    # Build the initial membership structure.
    for x in set(initial):
        if cnt[x] == 0:
            continue
        for d in divisors[x]:
            if queried[d]:
                buckets[d].add(x)

    answer = 0

    for k in queries:
        current = buckets[k]

        # The current k cannot receive new elements while it is being
        # processed, because x % k == 0 implies (x + 1) % k != 0.
        for x in list(current):
            c = cnt[x]
            if c == 0:
                continue

            answer += c

            cnt[x] = 0
            cnt[x + 1] += c

            # x is no longer occupied.
            for d in divisors[x]:
                if d != k and queried[d]:
                    buckets[d].discard(x)

            # x + 1 is now occupied.
            for d in divisors[x + 1]:
                if queried[d]:
                    buckets[d].add(x + 1)

        current.clear()

    print(answer)

if __name__ == "__main__":
    solve()
```频率数组是算法中值分组思想的直接实现。 什么时候`cnt[x]`不为零，所有这些动物在当前回合中都有相同的行为，因此一个转换代表所有动物。 

这`divisors`sieve 构建维护桶所需的关系。 例如，如果`x = 12`，相关集合包括那些`2`,`3`,`4`,`6`， 和`12`。 除数为`x`正是一个查询值，可以在该堆位于时选择该堆`x`。 

字典`buckets`使用而不是为每个整数分配一个集合，直到`400000`。 只有实际显示为查询的值才需要可搜索。 这节省了大量的 Python 对象开销。 

这`list(current)`转换是经过深思熟虑的。 在处理一个集合的同时改变其他集合中的成员资格是很难推理的。 更具体地说，当前桶在本轮中无法获得新值，因为如果`x`可以整除`k`， 然后`x + 1`不能被整除`k`。 拍摄快照还可以使迭代独立于处理另一个值引起的突变。 

答案存储在Python的整数类型中，因此不存在溢出问题。 理论答案可以达到`n * m`，即`10^10`，已经超出了有符号的 32 位整数。 

上限`MAXV = 400000`来自最大初始值`300000`每个最多加上一个增量`100000`回合。 该数组有两个额外的位置，因为转换使用`x + 1`。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(V log V + U D log V)`| 除数筛处理所有倍数，而每个处理的不同值都通过其除数 | 进行更新。 
| 空间|`O(V log V)`| 除数列表和动态除数桶存储值-除数关系 |

 这里`V = 400000`， 和`D`是此范围内的值的最大除数计数。 值域由约束条件确定，因此该筛子是实用的。 动态结构处理不同的当前桩尺寸，而不是所有桩尺寸`n`动物，这是使模拟可行的关键减少。 

官方 Codeforces 实例有 5 秒限制和 512 MB 内存限制。 尽管最初的竞赛主要是围绕较低级别的语言设计的，但 Python 版本受益于相对较小的值范围和相等的分组。

 ## 边缘情况

 对于第一个边缘情况，考虑一堆从未被选择的：```
1 1
1
2
```初始频率为`cnt[1] = 1`。 桶用于`2`不包含`1`， 因为`1`不能被整除`2`。 桶是空的，所以答案仍然存在`0`。 该算法不执行任何不必要的增量。 

对于相同值多次出现的情况，请考虑：```
3 3
2
2
2
2
3
4
```最初`cnt[2] = 3`，以及桶`2`仅包含值`2`。 第一个查询添加`cnt[2] = 3`到答案并将整个频率移动到`cnt[3]`。 下一个查询是`3`，所以桶为`3`包含`3`，又加了三块石头。 最终查询`4`同样地移动所有三只动物。 答案是`3 + 3 + 3 = 9`。 该算法仅用三个值转换来处理所有三种动物。 

对于动态创建值的情况：```
2 3
1
2
2
2
3
```第一个查询看到值`2`，将其移至`3`，并插入`3`放入除数桶中`3`。 第二个查询是另一个`2`，但当前值为`1`和`3`，所以没有任何改变。 第三次查询发现`3`并将其移动到`4`。 最终的答案是`2`。 

对于上边界，初始值可以是`300000`并且最多可以增加`100000`次，所以`400000`是可以出现的最大值。 实现分配通过`400001`并使用执行每个转换`x + 1`，因此最终可能的值被安全地表示。 答案可以大到`10^10`，Python 直接处理，不会溢出。
