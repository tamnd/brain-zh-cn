 ## 解决方案
 ## 问题理解

 输入描述了一个迷宫，其墙壁是对角绘制的。 每个字符位置都是 ASCII 表示形式中的一个小方块。 点表示正方形不包含墙。 斜线或反斜线是该正方形内的对角墙段。 斜线方向上的奇偶条件保证相邻的对角墙一致地相交，并且不会产生不明确的交叉。 任务是移除尽可能少的墙段，以便迷宫的每个区域都有通往外部的路径。 

思考迷宫的有用方法不是根据原始角色，而是根据自由空间的连接区域。 假设当前迷宫有 (k) 个不相连的区域，其中外部就是其中之一。 移除一堵墙最多可以连接两个区域，因此至少需要 (k-1) 堵墙。 相反，可以移除分隔两个不同区域的每面墙来合并它们，因此 (k-1) 次移除就足够了。 因此，整个问题被简化为计算连接区域。 

官方给出的问题是(1 \le r,c \le 1000)，所以输入最多可以包含(10^6)个字符。 检查每个输入字符的恒定工作量的解决方案是合适的。 具有 (O((rc)^2)) 工作量的算法将在最大尺寸下达到大约 (10^{12}) 次操作，并且完全不合适。 原始竞赛语句使用 5 秒时间限制和 512 MB 内存。 

简单的网格实现可能会在几个几何细节上出错。 对角墙不能简单地视为一个块字符单元，因为该对角线的两侧属于不同的区域。 例如，最小的封闭迷宫是```
2 2
/\
\/
```答案是`1`。 将每个斜线视为普通的块网格正方形会丢失对角线几何形状，并且可能错误地报告不存在封闭区域。 

第二种边缘情况是迷宫，其对角墙接触外边界但不形成封闭区域。 例如，```
1 1
/
```有答案`0`。 单个对角线段从一个边界角延伸到另一个边界角，因此两侧都保持与外部的连接。 如果粗心的实现将每个斜杠都算作创建单独的封闭单元格，则会返回错误的答案。 

相反的安排也很重要：```
2 2
\/
/\
```有答案`0`。 四个对角线段在此方向上不围绕内部区域。 假设每个密集的斜线组都会创建一个封闭区域的实现可能会错误地返回`1`。 

最后，一个完全开放的迷宫，例如```
1 1
.
```已经由一个区域组成，即外部连接区域，所以答案是`0`。 这会捕获意外计算空闲子单元数量而不是连接组件数量的实现。 

## 方法

 直接的暴力方法会尝试拆除墙壁并检查所有区域是否可以到达外部。 对于每个候选墙，我们可以暂时将其移除，对迷宫进行洪水填充，并测试每个空闲区域是否已与外部连接。 可能有 (rc) 堵墙，而连通性检查会触及 (O(rc)) 个迷宫位置，因此最坏的情况是 (O((rc)^2))。 在 (r=c=1000) 处，其运算量级为 (10^{12})。 暴力破解是正确的，因为它会在每次可能的更改后显式测试连接性，但重复的搜索使其无法使用。 

关键的观察是我们永远不需要决定要拆除哪些特定的墙。 如果初始迷宫有 (k) 个连接的自由空间区域，则正好 (k-1) 个墙就足够了。 移除一堵墙可以合并两个区域，从而将组件数量减少一。 重复此操作，直到仅保留外部连接区域需要 (k-1) 次移除，并且没有解决方案可以使用更少的移除。 

剩下的就是准确计算这些区域。 对角线表示在原始（r \times c）字符网格上变得很尴尬，因为移动发生在对角墙周围。 我们可以通过在两个方向上将表示缩放两倍来消除几何复杂性。 这是竞赛分析中描述的标准变换：每个输入字符变成一个（2×2）块，沿相应对角线的两个单元格被标记为墙，并且在整个迷宫周围添加一个空边界。 

为了`/`，被阻挡的单元格是其 (2 × 2) 块的右上角和左下角单元格。 为了`\`，它们是左上角和右下角的单元格。 一个点使所有四个单元格都空闲。 扩展网格中的运动是普通的四向运动，因此对角墙现在的行为与物理障碍完全相同。 

额外的空边界代表了无限的外部。 它保证每个可以逃离迷宫的区域都连接到一个公共组件。 然后我们可以洪水填充扩展的网格并计算其连接的组件。 答案是组件的数量减一，因为一个组件是外部的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| --- |
 | 蛮力 | (O((rc)^2)) | (O(rc)) | 太慢了|
 | 扩展网格洪水填充| (O(rc)) | (O(rc)) | 已接受 |

 ## 算法演练

 1. 读取 (r \times c) 字符网格并创建大小为 ((2r+2) \times (2c+2)) 的扩展网格。 额外的一个单元格边框故意留空，以便代表迷宫的外部。 
2. 将每个原始字符映射到其 (2 \times 2) 块。 对于点，将所有四个位置留空，因为没有墙。 为了`/`，将右上角和左下位置标记为墙壁。 为了`\`，将左上角和右下位置标记为墙。 缩放两倍使对角线壁足够厚，普通的四向运动无法穿过它。 
3. 扫描展开的网格。 每当发现未访问的空位置时，就从中开始洪水填充，并将每个可到达的空位置标记为已访问。 对于每个新的洪水填充，将组件计数增加一次。 
4. 将包含添加边界的组件视为外部区域。 每个其他组件都是一个封闭的或以其他方式断开的区域，需要连接到外部。 
5. 打印`components - 1`。 减法从计数中除去外部分量。 

### 为什么它有效

 扩展后的网格完全保留了原始迷宫的连通性。 原始迷宫中的路径对应于扩展表示中穿过自由单元的四向路径，而每个对角墙占据了阻止穿过它的通道所需的两个位置。 空的边界将所有离开迷宫的方式连接到一个外部组件中。 

假设扩展网格有 (k) 个连通分量。 其中之一是外部，留下必须与其连接的 (k-1) 个区域。 单次墙移除最多可以合并两个组件，因此少于 (k-1) 次移除是不够的。 另一方面，由于每个非外部组件都通过墙壁与其余组件分隔开，因此移除合适的分隔墙可以将其与另一个组件合并，并且重复此操作仅使用 (k-1) 次移除来连接所有 (k) 个组件。 因此最小值恰好是组件数量减一。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    r, c = map(int, input().split())
    maze = [input().strip() for _ in range(r)]

    h = 2 * r + 2
    w = 2 * c + 2

    # 0 = free, 1 = wall/visited
    grid = bytearray(h * w)

    # Convert every slash into two blocked cells in its 2x2 block.
    for i in range(r):
        row = maze[i]
        base = (2 * i + 1) * w + 1

        for j, ch in enumerate(row):
            p = base + 2 * j

            if ch == '/':
                grid[p + 1] = 1
                grid[p + w] = 1
            elif ch == '\\':
                grid[p] = 1
                grid[p + w + 1] = 1

    components = 0

    # The stack stores linear indices in the expanded grid.
    stack = []

    for i in range(h):
        start = i * w

        for j in range(w):
            pos = start + j

            if grid[pos]:
                continue

            components += 1
            grid[pos] = 1
            stack.append(pos)

            while stack:
                cur = stack.pop()

                nxt = cur - w
                if grid[nxt] == 0:
                    grid[nxt] = 1
                    stack.append(nxt)

                nxt = cur + w
                if grid[nxt] == 0:
                    grid[nxt] = 1
                    stack.append(nxt)

                nxt = cur - 1
                if grid[nxt] == 0:
                    grid[nxt] = 1
                    stack.append(nxt)

                nxt = cur + 1
                if grid[nxt] == 0:
                    grid[nxt] = 1
                    stack.append(nxt)

    print(components - 1)

if __name__ == "__main__":
    solve()
```实现的第一部分存储原始行并将扩展网格分配为一个`bytearray`。 平面字节数组比 Python 列表列表的内存效率要高得多，这一点很重要，因为当两个维度均为 1000 时，扩展网格可以包含大约 400 万个位置。 

表达式`p = base + 2 * j`标识与原始字符相对应的 (2 \times 2) 块的左上角单元格`(i, j)`。 为了`/`，被封锁的位置是`p + 1`和`p + w`。 为了`\`，他们是`p`和`p + w + 1`。 这些正是位于适当对角线上的两个单元格。 

边界从未明确标记为墙，因此整个外部框架从自由空间开始。 在洪水填充期间它成为外部组件。 

洪水填充使用线性索引而不是`(row, column)`元组。 垂直移动会改变索引`w`，水平移动时将其改变 1。 扩展后的网格有一个完全空的边框，因此访问`cur - w`,`cur + w`,`cur - 1`， 和`cur + 1`保持有效。 单单元格边框对于水平移动也很有用，因为即使是由外部行边界处的平面索引引起的过渡也会保留在显式表示的外部区域内。 

通过更改其字节来将位置标记为已访问`0`到`1`。 相同的字节值用于墙壁和访问过的单元格，因为两者都意味着洪水填充不得再次进入该位置。 在将单元推入堆栈之前对其进行标记可防止同一单元被多次插入。 

不使用递归。 递归 DFS 需要的递归深度与扩展单元的数量成正比，并且会超出 Python 对大型开放迷宫的递归限制。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O(rc)) | 扩展后的网格有 ((2r+2)(2c+2)=O(rc)) 个单元格，每个单元格最多被处理一次 |
