 ## 解决方案
 ## 问题理解

 我们给出了非负整数的多重集，但输入并没有显式列出所有元素，而是给出了达到某个值范围的频率。 我们也有一个目标值$n$，并且我们保证$n$目前不存在于多重集中。 

一个操作允许我们选择一组不同的值$T$当前存在于多重集中。 我们删除每个选定值的一次出现，然后计算$\mathrm{mex}(T)$，不包含在中的最小非负整数$T$，并将该数字插回到多重集中。 

任务是确定在多重集包含该值之前所需的此类操作的最小数量$n$至少一次。 

尽管该操作看起来像是操作整个多重集，但它仅取决于值是否存在，因为$T$是一组不同的值，每个选定的值仅贡献一次移除。 

约束条件$n \le 50$至关重要。 这意味着我们关心的状态空间实际上受到非负整数的小前缀的限制。 值大于$n$永远不会影响涉及的 mex 计算$n$，因为 mex 始终由从零开始向上的缺失值确定。 

当多重集已经有不小的间隙时，就会出现微妙的边缘情况。 例如，如果所有值来自$0$到$k-1$存在，则任意子集$T$包括所有这些产品$\mathrm{mex}(T) \ge k$，它可以直接跳过许多值。 相反，如果前缀中存在缺失值，则 mex 会被强制为该缺失值，而不管其中较大的元素如何$T$。 这使得贪婪的直觉变得不可靠，除非我们仔细推理可达状态。 

另一种边缘情况是频率极大时。 由于每个操作最多删除每个选定值的一个副本，因此多重性不会改变值的结构可达性； 只有一个值是否存在才重要。 尝试模拟实际多重集计数的简单解决方案将在大数据下失败$f_i$， 虽然$n$很小。 

## 方法

 强力解释将准确地模拟多重集。 每个操作都考虑所有子集$T$当前不同值的，计算 mex，应用删除，并重复直到$n$出现。 原则上这是正确的，但分支因子是巨大的：最多有 50 个相关值，有$2^{50}$每个步骤可能的子集，甚至修剪也不会保存它。 状态空间还包括重数，最多可达$10^{16}$，使得记忆变得不可能。 

关键的简化来自于观察到只有值的存在才重要，而不是存在多少个副本。 一旦一个值被完全删除，它就会保持不存在，除非作为 mex 重新引入。 因此，该过程可以看作是对存在值的二元向量进行操作$0$到$n$。 

现在操作变成：选择当前存在索引的子集，删除它们，然后插入等于该子集的 mex 的值。 这是一个经典的“集合压缩”动态，其中 mex 仅取决于所选子集中最小的缺失索引。 

关键的见解是我们正在尝试达到一种配置，其中$n$存在，从一组给定的当前值开始。 唯一的介绍方式$n$是执行一个操作，其中 mex 变为$n$，当所选子集包含来自的所有值时，就会发生这种情况$0$到$n-1$。 因此，要插入$n$，在某些时候我们必须能够形成覆盖整个前缀的子集。 

这将问题转变为确定需要多少步骤来“收集”所有缺失的前缀值，其中每个操作都可以用现有元素换取有助于填补空白的新 mex 值。 

形式化这一点的一种简洁方法是处理当前的当前值集并模拟 mex 驱动的插入如何增加小整数的覆盖范围。 每个操作都可以看作是选择一个我们能负担得起的前缀，删除它，然后添加它的 mex，有效地向上移动覆盖范围。 

因为$n \le 50$，我们可以安全地对子集的可达性进行建模$[0, n]$使用贪婪分层：每个操作最多可以修复一个“缺失前缀障碍”，并且最优策略总是首先尝试修复最小的障碍。 

由此产生的解决方案减少为重复检查最小缺失值并将其用作下一个 mex 目标，从而相应地更新集合。 这产生了一个具有线性步骤的确定性过程$n$。

 ## 算法演练

 我们将多重集压缩为布尔数组`present[i]`为了$0 \le i \le n$，因为只有这些值才重要。 

1. 构建值的存在数组$0$到$n$。 我们忽略大于的值$n$，因为他们从不帮助构建$n$。 这将问题简化为有界离散状态。 
2. 重复计算最小索引`mex_all`，这是中的第一个值$[0, n]$目前不存在。 这代表了我们在结构上缺失的下一个值。 
3.如果`mex_all == n`，我们完成了，因为$n$不在初始集中，但该过程已经发展，现在可以通过其 mex 恰好为的操作来生成它$n$。 我们停止计算操作。 
4. 否则，我们模拟一个操作，选择一个子集来强制创建`mex_all`。 从概念上讲，我们选择包含所有值的子集$0$通过`mex_all - 1`，确保其 mex 准确无误`mex_all`。 然后我们标记`mex_all`作为现在。 
5. 增加操作计数并重复。 

关键思想是，每一步都精确地解决一个缺失的前缀值，并且系统严格地朝着填充前缀的方向发展$[0, n]$。 

### 为什么它有效

 在任何时候，前缀中的最小缺失值都会充当障碍：避免删除所需元素的子集都不能产生比该值更小的 mex。 通过瞄准该障碍，每个操作都确定性地准确引入该缺失值，而不会使先前建立的较小值失效。 由于每一步都会增加当前前缀值的集合，并且前缀的边界为$n$，该过程必须终止至多$n$步骤。 任何操作都不能引入小于当前 mex 的值而不与其定义相矛盾，因此进度是单调的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        f = list(map(int, input().split()))
        
        present = [0] * (n + 1)
        for i in range(n):
            if f[i] > 0:
                present[i] = 1
        
        # we only care about 0..n-1 initially; n is missing by statement
        ans = 0
        
        while True:
            mex_all = 0
            while mex_all <= n and present[mex_all]:
                mex_all += 1
            
            if mex_all == n:
                print(ans + 1)
                break
            
            present[mex_all] = 1
            ans += 1

if __name__ == "__main__":
    solve()
```该代码将多重集压缩为布尔存在数组并完全忽略多重性。 每次迭代都会计算前缀上的全局 mex。 当那个墨西哥人变成$n$，我们考虑实际生产所需的最终操作$n$。 

最后一个微妙的点是`ans + 1`。 该循环仅模拟填充缺失前缀值的过程$n-1$。 最后一个操作是产生$n$，所以达到条件时单独计数。

 界限$n \le 50$即使对于 200 个测试用例，也可以轻松实现足够快的速度。 该算法避免了对频率大小的任何依赖。

 ## 边缘情况

 一个关键的边缘情况是最初缺少 0。 在这种情况下，mex 立即为 0，因此第一个操作必须先创建 0，然后才能进行其他操作。 该算法自然地处理这个问题，因为`mex_all`从 0 开始并立即插入。 

另一种情况是当多重集只包含大于0的值时。那么整个前缀开始为空，该过程确定性地先填充0，然后填充1，依此类推，直到达到$n$。 该算法通过重复插入当前的 mex 来反映这一点。 

最后，当初始集合已经包含完整的前缀时$n-1$，答案就是一次操作。 循环检测到`mex_all == n`立即并返回`ans + 1`，捕获最终的创建步骤，无需进行不必要的模拟。
