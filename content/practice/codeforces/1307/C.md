 ## 解决方案
 ## 问题理解

 我们得到一串小写英文字母。 消息是其选择的索引形成算术级数的任何子序列。 级数可以有任何正差，包括长度为一的特殊情况。 

任务不是找到消息本身。 相反，我们必须确定最频繁的隐藏消息出现的次数。 

乍一看，这看起来像是算术级数的子序列问题，这表明事情很复杂。 关键的观察是我们只需要所有隐藏字符串的最大频率，而不是字符串的身份。 

字符串长度可以达到$10^5$。 任何显式枚举算术级数、子序列或候选消息的解决方案都是不可能的。 甚至$O(n^2)$太大了。 我们需要接近线性时间的东西。 

一些边缘情况很容易被忽略。 

考虑：```
a
```唯一隐藏的信息是`"a"`，发生一次。 答案是：```
1
```仅计算长度至少为 2 的消息的解决方案将错误地返回零。 

考虑：```
aaaa
```消息`"a"`出现四次。 消息`"aa"`发生$\binom{4}{2}=6$次。 答案是：```
6
```仅跟踪单个字母的解决方案可能会忽略两个字母的消息可能更频繁地出现的情况。 

考虑：```
abab
```消息`"ab"`出现四次：$$(1,2),(1,4),(3,4),(3,2\text{ is invalid because order matters})$$更系统地，每早`a`以后可以配对`b`。 答案来自有序的字母对，不一定是相同的字母。 

关键的教训是最大频率可能来自一个字母字符串或两个字母字符串。 

## 方法

 暴力方法会尝试枚举隐藏消息并计算它们的出现次数。 即使将我们限制在算术级数上也无济于事。 子序列的数量呈指数级增长，并且长度的字符串内的算术级数的数量$10^5$是巨大的。 这是完全不可行的。 

突破来自于对问题中隐藏的定理的理解。 

假设隐藏消息的长度至少为三。 该消息的每次出现都包含第一个字符和最后一个字符。 如果我们忘记中间的字符，则每次出现都会映射到由这些端点形成的两个字母消息的出现。 

该映射是单射的。 较长消息的不同出现会产生不同的端点对。 这意味着任何长度至少为 3 的消息的出现次数不能超过某些两个字母消息的出现次数。 

因此，最常见的隐藏消息的长度必须为一或长度二。 

现在问题变得简单多了。 

对于长度一，我们只需要每个字符的频率。 

对于长度为 2 的情况，我们需要对每个有序字母对进行计数$(a,b)$，有多少对索引$i<j$满足：$$s_i=a,\quad s_j=b.$$只有26个小写字母，所以只有$26^2=676$有序对。 

我们可以从左到右处理字符串。 当我们看到一个角色时$c$, 每个以前见过的角色$x$创建该对的新出现$(x,c)$。 

这导致了线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 |$O(26n)$|$O(26^2)$| 已接受 |

 ## 算法演练

 1.维护一个数组`cnt[26]`在哪里`cnt[x]`是字母的次数`x`到目前为止已经出现了。 
2. 维护矩阵`pairs[26][26]`在哪里`pairs[x][y]`存储由字母组成的两个字母消息的出现次数`x`后面跟着字母`y`。 
3. 从左到右扫描字符串。 
4. 假设当前字符是`c`。 
5. 对于每一个字母`x`从`a`到`z`， 添加`cnt[x]`到`pairs[x][c]`。 

之前的每一次出现`x`可以与当前出现的`c`，产生一个新的消息出现`xc`。 
6. 增加`cnt[c]`一个。 
7. 处理整个字符串后，答案是所有条目中的最大值`cnt`以及所有条目`pairs`。 

### 为什么它有效

 对于单字母消息，`cnt[c]`正是该消息出现的次数。 

对于两个字母的消息，每个有效的出现对应于一对位置$i<j$。 当位置$j$已处理，位置$i$已经算在里面了`cnt`。 该算法只为该对添加一个贡献，并且不再计算它。 

剩下的问题是为什么较长的消息可以被忽略。 留言吧$t$长度至少为三个以字母开头$a$并以字母结尾$b$。 每次出现$t$确定两个字母消息的唯一出现$ab$使用第一个和最后一个选择的位置。 不同的情况出现$t$产生不同的端点对。 因此：$$\text{occurrences}(t) \le \text{occurrences}(ab).$$因此，长度至少为 3 的消息无法击败最好的单字母或两字母消息。 该算法会检查所有此类候选者，因此返回的最大值就是正确答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()

cnt = [0] * 26
pairs = [[0] * 26 for _ in range(26)]

for ch in s:
    c = ord(ch) - ord('a')

    for x in range(26):
        pairs[x][c] += cnt[x]

    cnt[c] += 1

ans = max(cnt)

for i in range(26):
    for j in range(26):
        ans = max(ans, pairs[i][j])

print(ans)
```数组`cnt`跟踪所有单字母消息。 矩阵`pairs`跟踪所有两个字母的消息。 

更新顺序很重要。 我们必须首先添加之前看到的角色的贡献，然后才增加当前角色的计数。 否则，角色可能会在同一位置错误地与自身配对。 

所有计数都适合 64 位整数。 在最坏的情况下，可能会出现以下两个字母的消息：$$\binom{10^5}{2} \approx 5 \times 10^9,$$这比 32 位限制大得多。 Python 整数会自动处理这个问题。

 ## 边缘情况

 考虑：```
a
```数组`cnt`变成`[1,0,...]`。 不会创建对计数。 最大值为 1，这是正确的。 

考虑：```
aaaa
```更新生成：$$pairs[a][a] = 1+2+3 = 6.$$单字母数只有 4。算法正确返回 6。 

考虑：```
abab
```当第二个`b`正在处理，已经有两个了`a`在它之前的字符，所以两个新的`ab`添加出现次数。 最终值`pairs[a][b]`变为 3，对应于以下对：$$(1,2),\ (1,4),\ (3,4).$$该算法对每个有效的有序对恰好计数一次。 

考虑：```
abcdefghijklmnopqrstuvwxyz
```每个角色出现一次。 每条两个字母的消息最多出现一次。 所有存储值中的最大值仍然是 1，这是正确答案。
