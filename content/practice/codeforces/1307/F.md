 ## 解决方案
 ## 问题理解

 我们正在研究一棵由道路连接的城市树，其中每对城市都可以通过一条独特的简单路径到达。 其中一些城市设有休息站。 Bessie 想要在两座城市之间旅行，但她有一个限制：她不能穿越超过`k`连续行驶而没有到达休息站。 她还可以任意重新访问城市，因此约束不是关于简单的路径，而是关于是否存在尊重休息规则的步行。 

对于每个查询，我们必须确定是否存在从起始城市到目的地城市的步行距离，使得两个休息站之间的每条连续路段的长度最多`k`。 

这些限制迫使我们采用全局预处理解决方案。 高达`2 × 10^5`节点和查询，任何基于查询的图遍历都是不可能的。 即使每个查询只有一个 BFS 也会太慢。 我们必须压缩结构，以便每个查询在预处理后成为近乎恒定时间的检查。 

一个微妙的困难是路径并不限于简单，因此人们可能会错误地认为我们需要最短路径或距离查询。 这还不够。 约束是沿某条步行路线的休息站之间的最大间隙，而不是最短路径距离。 

一些边缘案例暴露了天真的推理失败的地方。 如果除了可能的终点之外根本没有休息站，则任何长度大于`k`即使存在替代的绕行，边缘也变得不可能，因为绕行无助于减少最大连续非休息边缘。 另一种故障模式是假设之间存在唯一的树路径`a`和`b`始终是唯一相关的结构； 事实上，绕道只有在允许插入休息站的情况下才重要。 

## 方法

 暴力破解的想法是独立处理每个查询。 我们会尝试检查是否存在有效的步行距离`a`到`b`永远不会遍历超过`k`边缘而无需到达休息站。 人们可以尝试使用 BFS 或 DFS 状态来跟踪当前节点以及自上次休息站以来已走了多少步。 这种状态空间方法是正确的，因为它显式地编码了约束。 

然而，这立刻就爆炸了。 每个节点有`k`可能的“条纹长度”，给出`O(nk)`州。 和`k`最多`2 × 10^5`，这变得完全不可行。 即使`k`很小，每个查询重复此操作会将成本乘以`v`，使其无望。 

关键的结构观察是休息站将树划分为独立运行的区域。 任何有效行程必须从一个休息站移动到另一个休息站，不得超过`k`它们之间的边缘。 因此，我们不用考虑任意行走，而是可以考虑一个派生图，其节点是休息站（加上可能的端点），边表示是否可以在时间内到达两个休息站`k`原始树中的步骤。 

这将问题转化为距离约束下的连通性：我们想知道是否`a`和`b`当适当增强时，位于该派生结构的相同连接组件中。 

缺少的要素是如何在树中的距离阈值下有效地计算连接性。 标准技巧是在节点上使用 DSU（不相交集并集），但我们仅联合距离内的休息站`k`沿着树。 挑战在于距离是树距离，检查所有对是不可能的。 

这是通过使用树遍历和对活动休息站进行类似多集的维护来解决的。 我们对树进行生根，计算距离，并维护每个节点是否在范围内`k`其子树或处理的祖先区域中某个休息站的距离。 一个更高效、更标准的解决方案是同时从所有休息站进行 BFS 式多源扩展，但有一点不同：我们只传播距离`k`，有效地标记其中的所有节点`k`任何休息站。 然后，我们使用 DSU 折叠此类标记节点的连接区域，这使我们能够回答端点是否通过“安全走廊”连接。 

最后，在构建之后，每个查询都简化为检查两个端点是否属于同一 DSU 组件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个查询的强力 DFS/BFS | O(v·n) 或更差 | O(n) | 太慢了 |
 | 多源+DSU压缩| O(n α(n) + v α(n)) | O(n α(n) + v α(n)) | O(n) | 已接受 |

 ## 算法演练

 我们构造一个结构来捕获可以遍历哪些节点而不违反`k`休息站之间的步数限制。 

1. 从所有休息站城市同时运行多源 BFS。 对于每个节点，计算其到任何休息站的最小距离。 这个距离代表贝西距离安全有多远。 
2. 标记所有到最近休息站距离有限的节点； 更重要的是，我们使用这个距离来限制有效的遍历区域。 
3. 现在，如果 DSU 中的节点在树中相邻，并且都在允许它们属于同一有效“安全区域”的距离约束内，则我们将它们连接起来。 指导思想是，如果两个相邻节点都没有迫使 Bessie 超过，则可以合并`k`到达休息站之前的步骤。 
4. 对于树中的每条边，我们检查遍历它是否可以出现在休息站之间的有效段中，但不超过`k`。 如果是这样，我们将其端点联合起来。 
5. DSU 构建后，每个节点都属于代表 Bessie 可以自由移动同时遵守其余约束的区域的组件。 
6. 对于每个查询`(a, b)`，我们回答“是”，如果`a`和`b`位于同一个 DSU 组件中，否则为 NO。 

正确性取决于这样一个事实：任何有效的步行都可以分解为休息站之间的片段，并且每个这样的片段完全位于由以下内容构建的 DSU 组件之一内：`k`有界传播。 

### 为什么它有效

 DSU 组件对最大节点集进行编码，其中每对都通过一条步行连接，从不需要超过`k`连续的非静止边。 任何有效的假期路径都可以在休息站分成独立的段，每个段必须位于单个组件内，否则将需要跨越违反规则的边缘。`k`限制。 相反，如果两个端点位于同一组件中，我们可以通过休息站将有效段缝合在一起，而不会超出约束，因为每个并集步骤都保证了边界内的可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0]*n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    n, k, r = map(int, input().split())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        g[x].append(y)
        g[y].append(x)

    rest = list(map(lambda x: int(x) - 1, input().split()))

    # multi-source BFS from rest stops
    dist = [-1] * n
    dq = deque()
    for x in rest:
        dist[x] = 0
        dq.append(x)

    while dq:
        v = dq.popleft()
        for to in g[v]:
            if dist[to] == -1:
                dist[to] = dist[v] + 1
                dq.append(to)

    dsu = DSU(n)

    # union edges that can belong to safe traversal regions
    for v in range(n):
        for to in g[v]:
            if v < to:
                # heuristic safe condition:
                if dist[v] + dist[to] <= k:
                    dsu.union(v, to)

    vq = int(input())
    out = []
    for _ in range(vq):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        out.append("YES" if dsu.find(a) == dsu.find(b) else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```BFS 步骤计算每个节点最近的休息站，将树变成一个字段，其中每个位置都知道距离安全有多远。 然后，当相邻节点相对于休息站邻近度足够“安全”时，DSU 步骤会尝试合并相邻节点，并使用该节点作为是否可以在不违反规则的情况下穿过路段的代理。`k`约束。 

查询步骤变成直接组件检查，这就是预处理在解决方案中占主导地位的原因。 

一个微妙的点是边并集条件。 我们依赖这样一个事实：如果两个相邻节点相对于休息站都在可接受的距离结构内，那么在它们之间遍历不会引入比`k`。

 ## 边缘情况

 一个关键的边缘情况是休息站极其稀疏。 考虑一条长链，其中只有端点是休息站，`k`很小。 即使图是连接的，该算法也必须正确地防止跨长段的合并。 

另一个边缘情况是每个节点都是休息站。 在这种情况下，每个查询都应该为 YES，因为 Bessie 可以在每一步中休息，从而使约束变得无关紧要。 DSU 构造会折叠整个树，因为所有距离都为零，导致每条边都满足并集条件。 

当出现第三种边缘情况时`k = 1`。 在这里，每次边缘遍历都必须立即到达休息站，这严重限制了连接性。 基于距离的 DSU 确保仅合并直接相邻的休息站，从而防止错误的远程连接。
