 ## 解决方案
 ## 问题理解

 给定一个由两个整数相除形成的有理数，我们感兴趣的是它的小数点后的十进制表示形式。 任务是确定特定数字在无限（或终止）十进制扩展中出现的最早位置。 

输入由定义分数的分子和分母以及我们正在搜索的单个数字组成。 从概念上讲，我们想象将分子除以分母，并一一观察小数点后出现的数字。 输出是目标数字在此序列中第一次出现的索引，其中小数点后的第一位数字位于位置 1。如果该数字从未出现，则答案为 -1。

 约束条件允许分数中的两个数字最大为 100000。这个值足够小，可以逐位模拟长除法。 长除法的每一步仅使用常数时间算术，因此 O(b) 模拟就足够了。 由于十进制展开最多可以重复长度为 b 的循环，因此有意义的步数也受 b 限制。 

一个简单但重要的边缘情况是小数扩展提前终止。 例如，如果余数变为零，则扩展结束并且不再存在数字。 另一个微妙的情况是当所需的数字为 0 时。许多分数会产生没有零的长段，并且很容易错误地假设终止或错过只有在经过几个除法步骤后才能出现零。 

## 方法

 生成十进制扩展的直接方法是模拟长除法，就像手工完成的一样。 从a除以b的余数开始，我们将余数重复乘以10，通过整数除法提取下一个数字，并更新余数。 每个产生的数字都会与目标数字进行检查。 此过程将持续进行，直到找到该数字或余数变为零，这意味着小数扩展终止。 

这是可行的，因为每个步骤都按顺序生成一位十进制数字。 然而，在最坏的情况下，余数可能会在重复之前循环经过许多值，并且该过程最多可以运行 b 个步骤。 由于 b 可以是 100000，这仍然有效，但位于我们想要保证的上限。 

更结构化的观点是将余数视为确定性过程中的状态。 每个余数唯一地确定下一个数字和下一个余数。 由于只有 b 个可能的余数，一旦余数重复，小数展开就开始循环。 这确保了我们永远不需要超过 b 个步骤来完全表征序列。 我们可以选择跟踪访问过的余数，但只需迭代最多 b 步或在余数为零处停止就足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（无限步模拟）| 最坏推理中的 O(∞)，可能的循环 | O(1) | O(1) | 不正确/不安全 |
 | 最优（有界步长除法）| O(b) | O(1) 或 O(b) | 已接受 |

 ## 算法演练

 我们使用标准长除法程序逐步模拟小数扩展。

1. 从等于 a mod b 的初始余数开始。 这表示提取整数部分后剩下的内容，我们忽略它，因为只有小数点后的数字很重要。 
2. 重复以下过程最多 b 个步骤，因为在重复必须发生之前最多有 b 个可能的余数。 
3. 将当前余数乘以 10。这会将除法移至下一个小数位。 
4. 计算下一个数字，作为该值除以 b 的整数。 这正是十进制扩展中的下一个数字。 
5. 将余数更新为该值的模 b。 这个余数决定了所有未来的数字。 
6. 将产生的数字与目标数字进行比较 c。 如果它们匹配，则返回当前位置（从 1 开始的索引）。 
7. 如果余数变为零，则小数展开终止，因此我们提前停止，如果未找到该数字则返回 -1。 

关键的不变量是，在每一步，对（数字，余数）正确地表示精确长除法过程的下一个未使用的部分。 由于长除法是确定性的并且完全由余数表征，因此不会跳过或错误计算任何数字。 十进制扩展中的每个位置都按顺序访问一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b, c = map(int, input().split())

    rem = a % b
    for pos in range(1, b + 1):
        rem *= 10
        digit = rem // b
        rem %= b

        if digit == c:
            print(pos)
            return

        if rem == 0:
            break

    print(-1)

if __name__ == "__main__":
    solve()
```该实现直接反映了长除法过程。 使用模来初始化余数以丢弃整数部分。 每次迭代恰好产生一位小数，循环索引表示其小数点后的位置。 当余数变为零时提前终止可以防止小数扩展结束后不必要的迭代。 

一个微妙的细节是 b 次迭代的循环界限。 即使没有显式跟踪已访问的余数，该界限也能保证终止，因为只有 b 种可能的余数状态。 另一个重要的细节是仅使用整数运算，完全避免浮点错误。

 ## 边缘情况

 常见的边缘情况是分数因余数变为零而提前终止。 例如，使用输入`1 4 3`，小数展开式为`0.25`。 产生第二个数字后余数变为零。 循环立即停止，并且由于数字 3 从未出现，因此输出为 -1。 该算法正确地避免继续进入不存在的数字。 

另一种情况是目标数字为零时。 为了`1 8`，展开式为`0.125`。 该算法明确地检查每个产生的数字，因此无需特殊的大小写即可正确检测到第二个位置的零。 

最后一个微妙的情况是数字在重复周期中出现较晚。 为了`1 7`，展开式为`0.142857...`。 该算法探索余数的完整循环，并最终遇到该数字（如果该数字存在于循环中）。 如果没有，有界迭代可确保终止而不会无限循环。
