 ## 解决方案

 ## 问题理解

 我们得到了一个排列，我们从左到右查看它，只要一个位置的值严格大于之前看到的所有值，则将其标记为“记录”。 同样，记录是新前缀最大值出现的位置。 

我们可以从排列中删除一个元素。 删除后，剩余的序列被压缩，我们再次计算这个新序列中存在多少个记录位置。 任务是选择移除使该数字最大化的元素，如果多个元素给出相同的最佳结果，我们必须输出其中的最小值。 

输入大小高达 100000，因此对所有删除选择进行任何二次模拟都太慢。 在线性时间内尝试每次删除并重新计算记录计数的解决方案在最坏的情况下需要大约 10^10 次操作，这在两秒内是不可行的。 这立即推动我们寻求一种重用前缀信息并避免从头开始重新计算所有内容的解决方案。 

当数组非常小时，会出现微妙的边缘情况。 如果排列的大小为 1，则删除唯一的元素会留下一个空序列，并且唯一有效的答案是该元素本身。 另一个重要的情况是，删除较大的早期元素会更改许多后来的记录，因为它会降低前缀最大值并允许新记录比以前更早出现。 在这种情况下，在删除记录位置时仅减去一条记录的简单方法将失败，因为它忽略了后缀的阈值如何变化。 

## 方法

 直接方法很简单。 对于每个索引，删除该元素，重建数组，然后从左到右扫描计数前缀最大值。 这是有效的，因为定义是局部的：每个元素仅取决于先前的最大值。 然而，对每个删除进行重建和重新扫描会导致 O(n^2) 算法，因为 n 个候选中的每一个都会花费 O(n) 工作量。 

关键的观察结果是记录完全由运行最大值决定。 删除元素只会影响后缀中的比较，并且只能通过更改每一步的当前最大值来实现。 这意味着我们不需要为每次删除重建整个数组； 我们只需要了解跳过一个元素后运行最大值如何演变。 

构造此结构的一个有用方法是将位置分为原始数组中的记录和非原始数组中的记录。 如果我们删除一个非记录元素，所有原始前缀最大值在相同位置仍然有效，并且没有新元素可以比以前更早地成为记录，因为所有阈值都不变。 因此，此类删除始终保留相同数量的记录。 

如果我们删除一个记录位置，运行的最大序列就会改变。 下一个记录段可能会更早开始，因为阈值下降到前一个记录的值。 这可能会导致后缀中的多个新元素成为记录。 因此，只有记录位置才是可以改进答案的候选人。 

这将问题简化为，对于每个记录位置，当阈值降低到前一个记录最大值时，评估后缀中出现了多少新记录。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了|
 | 基于记录的评估| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们处理一次排列以识别所有记录位置并按顺序存储它们的值。 我们还跟踪每个位置的最大值，以便我们可以识别每个索引 O(1) 的记录。 

然后我们评估每个可能的删除。

1. 计算原始排列中的记录位置列表。 

如果位置 i 的值大于所有先前值的最大值，则该位置 i 是一条记录。 这给出了沿着数组的严格递增的记录值序列。 
2. 令记录位置为r1，r2，...，rk。 还将 prevMax[t] 定义为严格在 rt 之前的最大值，即 r(t-1) 的值，并将 prevMax[1] 视为 0。 
3. 考虑删除非记录元素。 

前缀最大值序列根本没有改变，因此记录数仍然是k。 这给出了一个基线答案，任何最佳解决方案都必须至少是这样好。 
4. 考虑删除位置rt 处的记录。 

这会删除一条保证记录，因此计数减一，但可能会在段 (rt, rt+1) 中创建新记录。 
5. 对于连续记录之间的每个段，模拟如果起始最大值降低到 prevMax[t]，有多少元素成为记录。

 扫描段并计算值超过当前运行最大值的元素，该最大值从 prevMax[t] 开始，并在找到新记录时更新。 
6. 在所有删除中取最好的结果，并在并列中选择被删除元素的最小值。 

### 为什么它有效

 该算法依赖于这样一个事实：记录位置根据运行最大值将数组划分为独立的单调段。 在每个段内，一个元素是否成为一条记录仅取决于进入该段的最大值。 删除非记录不会更改任何段边界条件，因此不会影响将来的比较。 删除一条记录仅更改一个边界条件，即下一段的起始最大值。 由于这是影响记录创建的唯一值，因此使用调整后的阈值评估每个记录位置可以准确捕获记录计数中所有可能的变化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    
    if n == 1:
        print(p[0])
        return

    # find record positions
    records = []
    max_so_far = 0
    is_record = [False] * n

    for i in range(n):
        if p[i] > max_so_far:
            is_record[i] = True
            records.append(i)
            max_so_far = p[i]

    k = len(records)

    # baseline: remove any non-record keeps k records
    best_count = k
    best_value = min(p[i] for i in range(n) if not is_record[i]) if k < n else p[records[0]]

    # try removing each record
    for idx, r in enumerate(records):
        prev_max = 0 if idx == 0 else p[records[idx - 1]]

        count = k - 1
        cur_max = prev_max

        i = r + 1
        while i < n:
            if p[i] > cur_max:
                count += 1
                cur_max = p[i]
            i += 1

        if count > best_count or (count == best_count and p[r] < best_value):
            best_count = count
            best_value = p[r]

    print(best_value)

if __name__ == "__main__":
    solve()
```该实现首先在一次传递中识别所有记录位置。 然后它分别评估两种类型的删除。 通过简单地检查哪些元素未标记为记录并选择其中最小的元素来计算非记录删除的基线。 

对于记录删除，代码显式模拟从删除的记录之后开始的后缀，但运行最大值初始化为前一条记录的值。 这直接匹配因删除该记录而引起的阈值变化。 

一个常见的陷阱是忘记删除记录后，下一个元素将与较小的最大值进行比较，这可能会显着增加记录数量。 内循环是完全捕获此效果的地方。

 ## 边缘情况

 对于单元素排列，算法立即返回该元素。 没有要分析的记录位置，删除它会产生唯一有效的输出。 

对于严格递增排列，每个元素都是一条记录。 删除第一个元素会将初始最大值从非常小的值降低到第二个元素，但这不会创建额外的记录，因此删除最小值是最佳选择。 

对于严格递减排列，只有第一个元素是记录。 删除它会将初始最大值降至零，并且每个元素都成为后缀扫描中相对于新基线的记录，该记录由剩余段上的模拟正确捕获。 

对于混合排列，例如交替高值和低值，删除记录位置会更改阈值，从而可以解锁后缀中的多个新记录。 该算法使用调整后的起始最大值显式地重新计算后缀，确保完全计算这些级联效应。
