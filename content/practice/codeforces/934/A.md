 ## 解决方案
 ## 问题理解

 两个玩家正在与两个整数数组进行交互。 一个玩家拥有一个长度为 n 的数组，另一个玩家拥有一个长度为 m 的数组。 每个数字代表灯笼的亮度，亮度可以是正值、负值或零。 

互动是对抗性的。 首先，第一个玩家从数组中永久删除一个值。 之后，第二个玩家从第一个玩家的数组中选择一个剩余值，并从自己的数组中选择一个值。 游戏的得分是这两个选定值的乘积。 第二个玩家试图最大化这个产品，而第一个玩家试图通过最初的移除来最小化它。 

输出是双方最优行动后的最终产品。 

约束很小，n 和 m 最多为 50。这立即表明，即使三次或二次方法也是安全的，而且解决方案可能取决于仔细分析极值情况，而不是大量的优化技术。 

负数会产生微妙的边缘情况。 由于乘积取决于符号，因此删除单个元素可以翻转剩余的一对成为最佳元素。 例如，如果第一个数组是`[1, -10, 2]`第二个是`[5, 6]`，去除`2`树叶`1`和`-10`，这会改变最佳产品是否来自配对大的正值或大的负值。 删除全局最大值或最小值的天真的贪婪方法在这里失败了，因为最佳删除取决于它如何重塑最佳可实现的产品。 

另一种边缘情况是两个数组都包含混合符号。 乘积最大值可能来自最大的正乘积或两个负乘积。 任何只考虑 max×max 的解决方案都会在输入上失败，例如`[-10, 1]`和`[-5, 2]`，其中最好的产品是`50`从`-10 × -5`。 

## 方法

 蛮力解释很简单。 我们尝试从第一个数组中删除每个可能的元素。 对于每个结果数组，我们考虑由简化的第一个数组中的一个元素和第二个数组中的一个元素形成的所有对，并计算可实现的最大乘积。 然后我们取所有移除量中的最小值。 

这是正确的，因为它直接模拟了双方玩家的最优策略。 第二个玩家总是选择可用于固定移除的最佳对，而第一个玩家评估所有移除。 

嵌套结构的瓶颈很明显。 有 n 种可能的删除，对于每个删除，我们最多扫描 (n−1) × m 对。 这导致 O(n²m)，当 n, m ≤ 50 时，最多约为 125,000 次操作，仍然很容易在限制范围内。 然而，我们可以做得更好，注意到删除一个元素后，第二个玩家总是从固定的第二个数组和修改后的第一个数组中进行选择，并且最佳选择仅取决于第二个数组的极值。 

对于固定的剩余第一数组，第二个玩家将始终将其中选定的元素 x 与第二数组中的最大值或最小值配对，具体取决于 x 的符号。 如果x为正，则最佳伙伴为b中的最大值； 如果 x 为负数，则最佳伙伴是 b 中的最小值。 这将每个配置的评估减少为扫描第一个阵列一次。 

改进是概念性的：我们没有枚举所有对，而是使用第二个数组的全局极值将内部最大化减少为常数时间决策。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²m) | O(1) | O(1) | 已接受 |
 | 最佳| O(n²) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们修正了这样的想法：从第一个数组中删除一个元素后，对手仅根据所选第一个数组元素的符号做出最佳反应。 

1. 计算第二个数组中的最大值和最小值。 这两个值就足够了，因为任何最佳配对都会根据符号使用其中一个值。 
2. 迭代第一个数组中的每个索引 i，将其视为要删除的元素。 
3. 通过扫描第一个数组中所有剩余元素来构造删除 a[i] 的效果。 
4. 对于每个剩余元素 x，计算它可以形成的最佳乘积：

 如果 x 非负，则贡献 x × max(b)，否则贡献 x × min(b)。 
5. 为此次删除取所有此类贡献的最大值。 
6. 跟踪所有移除的最小值。 

最终答案是所有最佳响应中的最小值。 

这种方法有效的关键原因是，对于任何固定的 x，对手的选择独立于所有其他元素。 第二个玩家永远不会从不同 x 值的混合选择中受益，因此第二个数组的全局极值完全描述了最佳响应。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    bmax = max(b)
    bmin = min(b)

    def best_value(arr):
        best = -10**30
        for x in arr:
            if x >= 0:
                best = max(best, x * bmax)
            else:
                best = max(best, x * bmin)
        return best

    ans = 10**30

    for i in range(n):
        reduced = a[:i] + a[i+1:]
        ans = min(ans, best_value(reduced))

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案预先计算第二个数组的极值一次，因为这些极值永远不会改变。 辅助函数通过单独检查每个剩余元素来评估第二个玩家对于任何固定的第一阵列配置的最佳响应。 

唯一微妙的实现细节是有效地处理删除。 由于 n 很小，因此对数组进行切片就足够了并且可以保持代码清晰。 内部基于标志的决定`best_value`是避免配对枚举的关键减少。

 ## 边缘情况

 一种关键的边缘情况是一个数组中的所有值均为负数。 在这种情况下，第二个玩家总是更喜欢与另一个数组中的最小（最负）值配对，因为它会产生最大的正乘积。 该算法可以正确处理这个问题，因为它仍然对每个负 x 计算 x × bmin。 

当两个数组都包含混合符号时，会出现另一种边缘情况。 在这里，最优策略根据元素进行切换，并且朴素的全局启发式方法失败了。 该实现正确地重新计算每个元素的最佳配对，而不是假设单个全局配对策略。 

最后的边缘情况是当删除单个元素时，改变哪个符号主导剩余的集合。 由于算法会从头开始重新计算每次删除的最佳值，因此自然可以处理这种转变，无需额外的逻辑。
