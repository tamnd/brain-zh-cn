 ## 解决方案
 ## 问题理解

 我们被要求构造一个不超过的正整数$10^{18}$这样，当它以 10 为基数书写时，其数字形成的“循环”总数恰好是$k$。 每个数字根据其形状提供固定数量的封闭区域：有些数字根本不封闭任何区域，有些数字封闭一个区域，还有一些数字封闭两个区域。 数字的总和就是所有数字的总和。 

该任务是建设性的：我们不是对给定数字的循环进行计数，而是构建任何数字，其按数字贡献的总和恰好等于所需值。 如果在大小限制内不存在这样的数字，我们必须输出-1。 

约束条件$k \le 10^6$是线性或贪婪结构的关键信号$k$是必须的。 一个数字最多$10^{18}$最多有 18 位数字，因此任何解决方案都必须仔细地将贡献打包成短数字序列。 

天真的思维的一个微妙的失败案例是尝试首先使用最大的循环数字贪婪地最小化数字计数，而不考虑小数字的可表示性约束$k$。 例如，如果假设每个循环都可以独立分解，而不考虑数字可用性，那么人们可能会错误地得出结论：所有$k$是可能的。 事实上，数字贡献是离散且有限的。 

## 方法

 每个数字贡献固定数量的循环：

 没有循环的数字是 1、2、3、5 和 7。数字 4 贡献 1 个循环。 数字 0、6 和 9 各贡献 1 个循环。 数字 8 贡献 2 个循环。 重要的结构观察是我们想要表示$k$作为值的总和$\{0,1,2\}$，但有一个限制，即我们正在构建一个数字，因此我们关心数字计数和词典结构，而不仅仅是分区。 

暴力方法会尝试枚举最多$10^{18}$，计算它们的循环计数并进行比较。 即使限制为 18 位数字，这也是$10^{18}$可能性，远远超出了可行性。 

关键的简化是翻转问题：我们不构造数字和计数循环，而是直接从循环单元构造数字字符串。 每个数字实际上都会“消耗”一定数量的循环，我们希望精确打包$k$循环成数字。 由于目标是任意有效数字，因此我们可以贪婪地选择数字，但我们还必须确保结果数字为正数且不超过 18 位数字。 

最佳策略是重复使用循环贡献最大的数字。 数字 8 为每个数字提供 2 个循环，这是最佳密度。 因此，我们首先使用尽可能多的 8，如果$k$是奇数，我们使用恰好贡献 1 个循环的数字来处理剩余的 1 个循环，例如 0 或 6 或 9 或 4。由于在有意义的结构中不允许使用前导零，因此我们确保第一个数字不为零。 

该结构简化为选择一种主要使用 8 的最小长度表示，如果有的话，最多有一个调整数字$k$很奇怪。

 ## 算法演练

 1. 观察每个数字贡献 0、1 或 2 个循环，因此构建大型循环的最有效方法$k$是最大限度地利用贡献 2 个循环的数字。 
2. 计算我们可以使用值 8 的多少位：这是$k // 2$。 每个这样的数字正好贡献 2 个循环，因此这占了大部分$k$。 
3.如果$k$是偶数，我们就只剩下 8 了。 这形成了具有最大循环密度的最小长度有效数。 
4.如果$k$是奇数，我们不能使用 8 来表示最后一个 1 循环。因此，我们减少 1 个 8（如果存在）或简单地附加一个 1 循环数字。 
5. 确保总位数不超过18。如果超过，则输出-1。 
6. 通过将所有数字按有效顺序排列来构建数字，确保第一位数字不为零。 

为什么它有效：不变量是在步骤 2 之后，我们已经表示了最大可能的偶数部分$k$使用最佳密度数字。 任何剩余的余数最多为 1，必须由单个 1 循环数字表示。 由于数字在循环贡献中是独立且相加的，因此重新排列数字不会影响正确性，只会影响数字的有效性。 该构造总是产生一个最小长度的有效数字多重集，其总和恰好为$k$，或者正确识别出它不能容纳在 18 位数字之内。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input().strip())

    # If k is 0, we cannot form a positive number
    if k == 0:
        print(-1)
        return

    # use as many '8' digits as possible (each contributes 2 loops)
    eights = k // 2
    rem = k % 2

    # total digits needed
    length = eights + rem
    if length > 18:
        print(-1)
        return

    digits = []

    # place one 1-loop digit first if remainder exists (avoid leading zero)
    if rem == 1:
        digits.append('4')  # or 6 or 9; any 1-loop digit works

    # fill remaining with 8s
    digits.extend(['8'] * eights)

    # ensure no leading zero issue (not relevant here since we don't use 0 first)
    print("".join(digits))

if __name__ == "__main__":
    solve()
```该代码直接实现了最大化使用数字8的贪婪思想。余数处理确保了奇偶校验的正确性$k$很奇怪。 数字 4 被用作单个后备，因为它只贡献一个循环并避免前导零的复杂性。 

长度检查强制执行$10^{18}$约束，因为任何有效的解决方案都必须在最多 18 位数字之内。

 ## 边缘情况

 一种边缘情况是当$k = 1$。 该算法分配$eights = 0$余数 1，产生一个数字“4”。 这正确地满足了要求并遵守 18 位限制。 

另一种边缘情况发生在$k$足够大$k // 2 > 18$。 在这种情况下，即使理论上可以形成循环，但数字限制会阻止构造。 例如，$k = 100$导致 50 位数字为 8，这违反了约束并正确返回 -1。 

第三个边缘情况是奇偶校验处理，当$k$很奇怪但是很大。 该算法确保恰好使用一个 1 循环数字，并且所有剩余的贡献都来自 8，因此总循环计数始终匹配$k$准确无误，无需进一步调整。
