 ## 解决方案
 ## 问题理解

 我们得到了几个由小写英文字母组成的短字符串。 对于每个字符串，我们需要根据字母如何在元音和辅音这两个类别之间交替的规则来确定它是否“有效”。 

该规则在预处理步骤后应用。 在 Wordland 中，如果同一个字母连续出现多次，则其发音就像是单次出现一样。 因此，首先通过将相同字母的每个最大块折叠成单个字符来压缩字符串。 压缩后，我们检查生成的序列是否在元音和辅音之间严格交替。 如果压缩字符串中的每个相邻对都包含一个元音和一个辅音，则单词是有效的。 

元音字母组固定为a、e、i、o、u、y，其他字母均为辅音。 

输入大小非常小：最多 100 个单词，每个单词的长度最多 100。这立即意味着即使是二次或三次解也能轻松通过，但任务的结构表明每个单词的线性扫描是自然的选择。 

主要的微妙之处在于压缩规则。 幼稚的方法可能会忘记在检查交替之前合并连续的重复项。 这会导致错误的拒绝或接受。 

例如，考虑单词“totoroooo”。 如果我们直接检查交替，则尾随的“oooo”看起来像连续的多个元音，这将违反交替。 但压缩后，“oooo”变成单个“o”，结构变成“to to or o”，正确交替。 

第二个边缘情况是像“rr”这样的单词。 压缩后变成“r”，没有相邻对违反规则，所以应该是有效的。 

## 方法

 蛮力的想法很简单。 对于每个单词，我们首先通过合并连续的相同字符来显式构建一个新字符串。 这可以通过扫描字符串并仅在与前一个字符不同时附加字符来完成。 压缩后，我们迭代减少的字符串并检查每个相邻的对，以验证一个是元音，另一个是辅音。 

这种方法对于每个单词的大小来说已经是线性的。 即使我们考虑最坏的情况，即 100 个长度为 100 的单词，我们也会执行大约 10,000 个字符操作，这也是微不足道的。 不需要更高级的优化。 

关键的观察结果是，问题本质上是每个单词两次独立的线性传递：一次用于游程压缩，一次用于验证。 由于两者都是 O(L)，我们可以从概念上将它们合并到一次扫描中。 在扫描时，我们跟踪最后保留的字符（压缩后），并且仅在新字符块开始时与其进行比较。 

暴力版本之所以有效，是因为它显式地构造了压缩表示。 优化版本避免存储它，而是仅保留最后一个相关字符及其元音状态。

 ## 算法演练

1. 对于每个单词，定义一个辅助函数来确定字符是否为元音。 这是针对集合 {a, e, i, o, u, y} 的恒定时间查找。 
2. 从左到右遍历单词的字符，同时保留我们接受的最后一个“压缩”字符。 最初，没有前一个字符。 
3. 当我们遇到一个字符时，将其与原始字符串中的前一个字符进行比较。 如果相同，我们就跳过它，因为它属于同一运行并且不会改变压缩结构。 
4. 如果它与前一个原始字符不同，我们将其视为压缩序列​​中的下一个字符。 此时，我们将其元音/辅音类型与最后保留的压缩字符进行比较。 如果两者属于同一类，我们立即知道该词是无效的。 
5. 更新最后一个压缩字符并继续扫描。 
6. 如果我们到达单词的末尾而没有发现违规，则该单词是有效的。 

关键的设计点是我们只比较在压缩边界中幸存下来的角色。 我们从不在一次运行中进行比较，因为这些重复项被明确忽略。 

### 为什么它有效

 游程压缩准确地保留了我们关心的序列：不同字母之间的转换。 任何对交替规则的违反都必须出现在这些转换之一上。 在一系列相同的字母中，所有字母都具有相同的元音状态，因此折叠它们不会丢失任何与交替相关的信息。 因此，仅检查压缩边界序列就足够且完整了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

VOWELS = set("aeiouy")

def is_vowel(c: str) -> bool:
    return c in VOWELS

n = int(input())
for _ in range(n):
    s = input().strip()
    
    prev_raw = None
    prev_kept = None
    
    ok = True
    
    for c in s:
        if c == prev_raw:
            continue
        
        if prev_kept is not None:
            if is_vowel(c) == is_vowel(prev_kept):
                ok = False
                break
        
        prev_kept = c
        prev_raw = c
    
    print("YES" if ok else "NO")
```该解决方案维护两个状态。 第一个，`prev_raw`，纯粹用于压缩：它跟踪当前字符是否是重复运行的一部分。 第二个，`prev_kept`, 表示压缩序列中的最后一个字符。 

关键细节是我们仅在出现新的压缩字符时比较元音类别。 这避免了构建显式字符串，同时仍然保持正确性。 

一个常见的错误是比较原始字符串中的每个相邻对，这会错误地惩罚重复的元音或辅音。 另一个错误是压缩但忘记仅在压缩边界后进行比较。

def run(inp: str) -> str:

    def is_vowel(c):
        return c in VOWELS
    
    n = int(sys.stdin.readline())
    out = []
    for _ in range(n):
        s = sys.stdin.readline().strip()

        prev_kept = None
        ok = True

                break

            prev_raw = c
        
        out.append("YES" if ok else "NO")

 ## 边缘情况

 一种边缘情况是完全由重复的相同字母组成的单词。 例如，输入“ttttt”压缩为“t”，它没有违反交替的转换，因此它是有效的。 该算法处理这个问题是因为`prev_kept`在出现第二个不同的压缩字符之前不会进行比较。 

另一个边缘情况是一个单词在多个地方出现重复，例如“lessoon”。 重复的“sss”必须折叠成单个“s”，否则简单的相邻检查将错误地检测到运行中的元音辅音违规。 在该算法中，使用跳过所有重复的字母`prev_raw`，确保只有运行边界有助于检查。 

第三种边缘情况是字母与重复块交替出现，例如“totoroooo”。 尾随的元音不得被解释为多次交替。 跳过逻辑确保仅考虑运行的转换，因此正确性仅取决于压缩结构而不是原始重复。
