 ## 解决方案
 # 问题理解

 锁是一棵树，其顶点涂有两种颜色。 移动可以重新绘制一个顶点，也可以删除当前所有顶点具有相同颜色的整个连接区域。 任务是找到直到没有顶点为止所需的最小移动次数。 输入给出顶点数、初始二值着色和树边。 输出是尽可能少的操作数。 

关键细节是树结构并没有要求我们模拟删除。 顶点数量可以达到 200,000 个，因此任何尝试许多可能的删除顺序或在每次操作后维护树的方法都不适合。 解决方案必须接近线性时间，因为即使是二次算法，在最大规模下也已经需要大约 400 亿次运算。 

有两种自然策略。 我们可以单独删除每个初始单色组件，或者我们可以花费操作重新绘制顶点，以便许多组件合并并一起消失。 挑战在于认识到部分重绘和部分删除的复杂组合无法击败这两种想法中最好的。 

考虑一棵具有四个星形顶点的树：```
4
1000
1 2
1 3
1 4
```最初有四个单色分量，因此将分量一一删除需要四步。 然而，重新绘制中心会使整棵树变白，最后一次删除会删除所有内容，给出的答案是 2。 仅计算组件数量的解决方案在这里失败了。 

另一个重要的情况是所有顶点已经具有相同的颜色。 例如：```
3
000
1 2
2 3
```答案是一，因为整棵树已经是一个可移动的组件。 在删除之前始终添加一次重绘的公式将错误地返回两次。 

相反的极端也很重要。 对于单个顶点：```
1
1
```答案是一。 不需要重新绘制，但是顶点仍然需要通过删除操作来删除。 

# 方法

 直接的暴力方法将尝试决定首先删除哪些组件以及重新绘制哪些顶点。 对于树的每种可能的状态，它可以尝试每种可用的操作并使用带有记忆的递归。 这是正确的，因为它探索了每个可能的序列，但状态数量随着顶点数量呈指数增长。 即使是小树也会产生太多可能的着色和剩余的顶点集，因此这种方法不可用。 

一个更简单的暴力想法是重复计算当前的单色组件并尝试每种可能的重新绘制。 这仍然会失败，因为每次重新绘制后，可能的选择数量仍然很大。 对于 200,000 个顶点，即使检查每个可能的单个顶点重绘也已经太昂贵了。 

重要的观察结果是，重新绘制只会有助于减少不同颜色组的数量。 只有两种颜色，因此如果我们决定将整个树设置为一种颜色，最便宜的选择是重新绘制不太频繁的颜色的每个顶点，然后删除树一次。 这花费：```
min(number of white vertices, number of black vertices) + 1
```另一种选择是根本不进行重新粉刷。 那么每个初始单色连通分量最终都必须被删除，因此成本等于此类分量的数量。 

令人惊讶的是，混合这两种策略并不能改善答案。 如果我们重新绘制的顶点数少于少数颜色数，则两种颜色的一些顶点都会保留。 剩余的不同颜色的区域仍然需要单独删除，并且总数不能胜过简单地删除所有初始组件。 如果我们重新绘制足够多的顶点以完全删除一种颜色，那么我们至少已经付出了使整棵树变成单色的成本。 

因此，该解决方案被简化为在一次遍历中计算两个值：单色分量的数量和每种颜色的顶点数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 # 算法演练

 1. 计算每种颜色有多少个顶点。 这给出了我们从树中删除一种颜色、重新绘制另一种颜色并执行最终删除的策略的成本。 
2. 遍历树一次并计算单色连通分量。 从每个未访问过的顶点开始遍历。 所有具有相同颜色的可达顶点都属于同一组件。 
3. 计算两个可能的答案。 第一个是单色分量的数量。 第二个是不太常见颜色的顶点数量加上一次最终删除操作。 
4. 输出这两个值中较小的一个，因为每个最优序列都被这两种情况之一覆盖。 

为什么它有效：

 每次删除操作都会删除当前树的一个单色连通分量。 如果我们永远无法完全消除某种颜色，则剩余的颜色边界将迫使我们至少付出与处理原始组件相同的成本。 避免这些组件边界的唯一方法是重新绘制足够的顶点，以便整棵树变成一种颜色。 最便宜的此类变换会重新绘制较小颜色类的所有顶点。 之后，一次删除即可删除所有内容。 由于每个最佳解决方案必须要么保留两种颜色，要么完全去除一种颜色，因此这两种成本中的最小值始终是可以实现的，并且无法改进。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    graph = [[] for _ in range(n)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        graph[a].append(b)
        graph[b].append(a)

    count0 = s.count('0')
    count1 = n - count0

    components = 0
    visited = [False] * n

    for i in range(n):
        if not visited[i]:
            components += 1
            color = s[i]
            stack = [i]
            visited[i] = True

            while stack:
                v = stack.pop()
                for u in graph[v]:
                    if not visited[u] and s[u] == color:
                        visited[u] = True
                        stack.append(u)

    repaint_strategy = min(count0, count1) + 1
    print(min(components, repaint_strategy))

if __name__ == "__main__":
    solve()
```代码的第一部分使用邻接表构建树。 一棵树正好有`n - 1`边，因此将每条边存储两次可以得到线性的内存使用量。 

颜色计数足以评估完整的重绘策略。 我们永远不需要知道哪些特定顶点被重新绘制，因为只有每种颜色的顶点总数才重要。 

DFS 对单色分量进行计数。 当发现一个新的未访问顶点时，它会开始一次组件遍历。 DFS 仅将边跟踪到具有相同颜色的顶点，因此相反颜色的顶点自然地将树分成不同的组件。 

组件计数中不存在差一问题，因为每个顶点都被访问一次，并且每次遍历开始都对应一个组件。 Python 整数还可以处理最大计数，而无需担心溢出。

 # 边缘情况

 对于星形树：```
4
1000
1 2
1 3
1 4
```该算法对四个单色分量进行计数。 它还计算一个黑色顶点和三个白色顶点，从而产生两个操作的重绘策略。 最小值为 2，与重新绘制中心和删除整棵树的顺序相匹配。 

对于完全单色树：```
3
000
1 2
2 3
```遍历找到一个组件。 重绘策略将花费四，因为没有黑色顶点可以重绘，并且公式变为`0 + 1 = 1`。 答案仍然是一，因为树可以立即被删除。 

对于尽可能最小的输入：```
1
1
```遍历只创建一个组件。 重绘策略也给出了1，所以最终的答案是1。 该算法不会意外返回零，因为始终需要删除才能删除最终顶点。
