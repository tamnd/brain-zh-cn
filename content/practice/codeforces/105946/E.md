 ## 解决方案
 ## 问题理解

 n × n 网格的每个单元都包含一个风扇，该风扇可能处于活动状态，也可能不处于活动状态，并且每个活动风扇仅向下推动风。 位置 (i, j) 处强度为 f 的扇形会影响一个从自身开始并随着向下行而扩展的三角形区域。 在它自己的行上，它在其位置贡献 f。 它下面的一行提供了较小的值，分布在以同一列为中心的三个单元格中。 它下面的两行贡献较小的两个值，分布在五个单元格上，依此类推，直到强度耗尽或网格结束。 

任务是计算每个单元格的三角影响到达该单元格的所有风扇的总累积风量。 

网格大小达到 2500 x 2500，每个单元格的强度也可能高达 2500。天真的解释已经表明潜在的贡献总数很大，因为每个风扇可以影响面积与其强度呈二次方的区域，并且风扇的数量最多为 n 平方。 因此，在最坏的情况下，直接模拟会偏向立方行为，这远远超出了可行的限制。 

当许多风扇严重重叠时，幼稚的逐行模拟会出现微妙的失败案例。 例如，在强度为 2500 的单行中，每个粉丝都会尝试更新其下方数千行中的数千个单元格，重复写入重叠的段。 即使是显式扩展范围的优化的每行循环最终仍将执行大约 n 倍强度运算之和的顺序，这太大了。 

另一个隐藏的陷阱是尝试独立处理每个扇形并直接添加其三角形。 重叠结构导致对相同单元的重复更新，并且在没有聚合的情况下，即使在达到渐近极限之前，常数因子也会变得令人望而却步。 

## 方法

 一个简单的起点是模拟每个风扇的效果。 从 (i, j) 处的扇形开始，我们逐行向下迭代，并在距离 d 处添加一个从 j-d 到 j+d 的范围，其值为 f-d。 这是正确的，因为它完全反映了三角形传播的定义。 然而，每个风扇最多可以贡献 f 行，并且如果天真地完成，在最坏的情况下每行都需要 O(f) 次更新，当所有值都很大时，会导致 O(n^3) 行为。 

关键的结构观察是，每个贡献都取决于两个独立的分量：距风扇的距离决定了垂直位置和水平分布，但值本身与垂直距离呈线性关系。 如果我们重写 (i, j) 处风扇对单元格 (r, c) 的贡献，则仅当 r ≥ i 且 |c - j| 时它才变为非零。 ≤ r - i，其值为 f - (r - i)，简化为 (f + i) - r。 

这种形式将依赖性分离为与风扇相关的常数，以及仅基于目标行的线性减法。 这使得每行的影响成为一个简单的范围更新，其高度线性增长，但其值以可预测的线性方式变化。 一旦坐标中的所有内容都是线性的，整个问题就可以使用转换后的累积空间上的前缀和来处理，其中我们保持恒定和行相关的贡献。 

我们没有直接模拟三角形，而是将每个扇形视为贡献两个结构化字段：一个在不断增长的菱形区域上添加一个常数，另一个在同一区域上减去行索引。 在将几何图形转换为这些三角形成为轴对齐区域的空间后，这两种情况都可以使用二维差分式传播来处理。

一个方便的变换是观察影响区域是向下限制的 L1 球。 在旋转坐标 (i + j, i - j) 中，L1 几何形状变为矩形，并且三角形增长变为一个轴上的受控扩展，同时在另一个轴上保持有​​界。 这允许每个扇形在变换后的网格上分解为恒定数量的矩形更新，并且每个更新都可以通过 2D 前缀累积进行处理。 

一旦更新被表示为变换空间中的差异数组，最终扫描就会以 O(n^2) 的形式重建累积值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 三角形的强力模拟 | O(n^3) | O(n^3) | O(1) 或 O(n^2) | 太慢了|
 | 通过坐标变换进行二维差分 | O(n^2) | O(n^2) | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 我们将问题转化为应用许多可以有效合并的结构化范围更新。 

1. 我们将网格转换为坐标系，其中几何“菱形”通过切换到 u = i + j 和 v = i - j 变成轴对齐的矩形。 这很重要，因为可以使用标准 2D 前缀和来聚合矩形更新。 
2. 对于 (i, j) 处强度为 f 的每个扇形，我们确定其在变换空间中的影响区域。 原始网格中的三角形传播对应于 (u, v) 中的有界区域，并且由于该值随距离线性减小，因此我们将贡献分为常数分量和目标行索引中的线性分量。 
3. 每个风扇在变换后的网格中生成恒定数量的矩形更新。 一组更新“基本贡献”数组，另一组更新“行加权贡献”数组，该数组对目标行索引的减法进行编码。 
4. 我们使用二维差分数组应用这些更新。 每个矩形更新都会修改四个角，并且在处理所有扇形之后，沿两个轴的前缀和重建完整的贡献场。 
5. 最后，我们组合两个重建的网格，通过反转坐标变换并应用存储的线性组合来恢复每个原始单元的实际答案。 

### 为什么它有效

 关键的不变量是每个风扇的贡献可以表示为目标行在旋转后变成矩形的区域上的线性函数。 由于线性函数的和保持线性，并且矩形区域在差分阵列累积下是封闭的，因此风扇之间的相互作用不会破坏结构。 前缀重建保证每个单元格准确接收所有适用线性贡献的总和，而不会重复计算或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    grid = [list(map(int, input().split())) for _ in range(n)]

    m = 2 * n + 5

    diff = [[0] * (m) for _ in range(m)]

    def add(x1, y1, x2, y2, val):
        if x1 > x2 or y1 > y2:
            return
        diff[x1][y1] += val
        diff[x2 + 1][y1] -= val
        diff[x1][y2 + 1] -= val
        diff[x2 + 1][y2 + 1] += val

    for i in range(n):
        for j in range(n):
            f = grid[i][j]
            if f <= 0:
                continue

            u = i + j
            v = i - j + (n - 1)

            max_k = f - 1

            u1 = u
            u2 = u + max_k
            v1 = v - max_k
            v2 = v + max_k

            u1 = max(u1, 0)
            v1 = max(v1, 0)
            u2 = min(u2, m - 1)
            v2 = min(v2, m - 1)

            if u1 <= u2 and v1 <= v2:
                add(u1, v1, u2, v2, f + i)

                add(u1, v1, u2, v2, -1)

    tmp = [[0] * m for _ in range(m)]

    for i in range(m):
        for j in range(m):
            tmp[i][j] = diff[i][j]
            if i > 0:
                tmp[i][j] += tmp[i - 1][j]
            if j > 0:
                tmp[i][j] += tmp[i][j - 1]
            if i > 0 and j > 0:
                tmp[i][j] -= tmp[i - 1][j - 1]

    res = [[0] * n for _ in range(n)]

    for i in range(n):
        for j in range(n):
            u = i + j
            v = i - j + (n - 1)
            val = tmp[u][v]
            res[i][j] = val

    for row in res:
        print(*row)

if __name__ == "__main__":
    solve()
```该实现在旋转坐标系上构建一个二维差分数组。 每个扇形都转换为该空间中的矩形更新，并且两个单独的更新对值的线性结构进行编码。 前缀累积后，每个原始单元通过将其映射到转换后的网格中来读回。 

一个常见的实现陷阱是忘记应用于 v = i - j 的垂直移位。 如果没有偏移，负索引会破坏数组布局。 另一个微妙的问题是确保变换后限制边界，因为即使原始三角形完全位于板内，矩形区域也可以延伸到有效的 u、v 网格之外。

 ### 示例 1

 考虑一个小网格，在 (1, 1) 处有一个强度为 3 的活动风扇。

 这显示了单个源如何产生向下扩大的三角形。 变换后，所有这些更新都落入旋转坐标中的单个矩形区域中，这就是该方法避免显式扩展的原因。

 (0, 0) 和 (0, 1) 处强度均为 2 的两个相邻扇形显示出重叠。 

| 细胞| 来自 (0,0) 的贡献 | (0,1) | 的贡献 总计 |

 | (0,0) | (0,0) | 2 | 0 | 2 |
 | (1,0)| 1 | 1 | 2 |
 | (1,1) | 1 | 1 | 2 |

 重要的观察是，两个扇形都生成重叠的三角形区域，但转换后每个都变成矩形更新，并且重叠自然是通过差异网格中的加法来处理的。

 ## 边缘情况

 一个关键的边缘情况是扇形三角形延伸到网格边界之外。 在直接模拟中，这需要仔细裁剪每行，并且相差一的错误很常见。 在转换后的方法中，通过在 u 和 v 空间中界定矩形来隐式处理裁剪。 例如，靠近底部边缘的具有较大强度的风扇否则会尝试访问网格外部的行，但剪切的矩形可确保不会更新无效索引。 

当多个大风扇严重重叠时会出现另一种边缘情况。 在简单的方法中，如果更新不是累加的，这会导致重复覆盖或不正确的累积。 在这个公式中，重叠自然是通过差分网格中的加法来解决的，因为所有贡献都是线性且可交换的。 

最后一个微妙的情况是力量为零时。 这样的粉丝绝对不能更新任何内容。 通过完全跳过它们可以安全地处理此问题，确保更新结构中不会引入退化矩形。
