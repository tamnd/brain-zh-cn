 ## 解决方案
 ## 问题理解

 给定一个整数数组，我们需要计算有多少个不同索引的有序三元组形成算术关系，其中两个选定元素的总和等于数组中的第三个元素。 正式来说，我们选择三个不同的位置$i, j, k$并检查是否$a_i + a_j = a_k$，分别计算每个有效订单。 

数组中隐藏着一个关键的结构限制：每个值最多有三个正除数。 这立即迫使每个元素变成仅有的三种形状之一。 数字 1 有一个约数。 质数恰好有两个约数。 素数的平方正好有三个约数。 没有其他整数满足条件，因此每个数组元素都必须属于这三个类别之一，即使值本身可以大到$10^{18}$。 

约束允许最多$2 \cdot 10^5$元素，这排除了在原始索引的最坏情况下任何三次甚至二次的解。 对索引的直接三重循环将按以下顺序执行$n^3$的操作，远远超出了可行的限度。 即使是对索引对的简单双循环也已经接近$4 \cdot 10^{10}$在最坏的情况下，操作通常仍然太慢，除非数据结构被大量利用。 

主要的微妙之处在于指数很重要，而不仅仅是价值。 如果一个值多次出现，则每次出现都被视为不同的选择，因此必须小心处理多重性。 

通常打破朴素推理的边缘情况是重复和排序。 例如，如果数组是$[1, 2, 3, 3]$，则方程$1 + 2 = 3$根据选择的 3 的出现次数贡献多个有效的三元组。 另一个例子是当同一个值出现多次时，例如$[2, 2, 4]$。 这对$(2, 2)$贡献不同于$(2, 4)$，并且忘记索引的独特性或多重性会导致错误的计数。 

## 方法

 蛮力方法会尝试每个有序的索引三元组$(i, j, k)$并检查总和条件是否成立。 这是正确的，因为它直接强制执行所有约束，包括不同的索引和排序。 但是，它执行三个嵌套循环，导致$O(n^3)$时间，这甚至变得不可行$n = 200{,}000$。 

一个自然的改进是修复第三个索引$k$， 对待$a_k$作为目标和，然后计算有多少个有序对$(i, j)$满足$a_i + a_j = a_k$。 这将问题简化为计算每个固定目标的有效对。 如果我们存储值的频率，我们可以使用乘法而不是扫描索引来计算贡献。 

关键的见解是我们不再需要单独推理位置。 一旦对值进行分组，每对值都会贡献可预测数量的索引对，这些索引对的数量纯粹由频率决定。 这将问题转化为基于频率的值卷积。 

困难转移到有效查找每个值$c$, 有多少对$(x, y)$数组中满足$x + y = c$。 通过频率图，这变成了不同值的结构化枚举。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^3)$|$O(1)$| 太慢了|
 | 频率对计数 |$O(m^2)$在哪里$m$是不同的值|$O(m)$| 结构下接受|

 这里$m$是不同值的数量，它明显小于$n$在实践中由于除数约束结构。 

## 算法演练

 ### 1. 统计每个值的频率

 我们首先建立一个频率图`freq[v]`，存储每个值出现的次数。 这是必要的，因为每个索引都是不同的，并且多重性直接影响可以形成多少个三元组。 

### 2. 迭代所有有序的不同值对

 我们考虑每个有序的值对$(x, y)$，包括以下情况$x = y$。 对于每一对，贡献该值对的索引对的数量为：

 -`freq[x] * freq[y]`如果$x \neq y$-`freq[x] * (freq[x] - 1)`如果$x = y$这正确地计算了有序索引选择$(i, j)$和$i \neq j$。 

### 3. 计算所需的第三个值

 对于每对$(x, y)$, 计算$z = x + y$。 我们检查是否$z$使用频率图存在于数组中。 

如果存在，则每个有效对$(i, j)$贡献`freq[z]`索引的选择$k$，因为任何发生$z$可以作为第三个元素。 

### 4. 累积贡献

 我们添加`pair_count * freq[z]`每个有序值对的答案。 

索引冲突不需要额外的修正，因为$z = x + y$不能等于任何一个$x$或者$y$对于正整数，因此第三个索引自动不同于前两个索引。 

### 为什么它有效

 每个有效的三元组$(i, j, k)$唯一对应于值的选择$(x, y, z)$这样$x + y = z$，以及每个值出现的索引选择。 该算法将每个可能的有序值对精确地枚举一次，并乘以第三个值的所有兼容出现。 由于索引仅在不相交的频率组内选择，并且相等条件是通过组合计数处理的，因此每个有效的三元组仅计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import Counter

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    freq = Counter(a)
    vals = list(freq.keys())
    
    ans = 0
    
    for i in range(len(vals)):
        x = vals[i]
        fx = freq[x]
        for j in range(len(vals)):
            y = vals[j]
            fy = freq[y]
            
            if x == y:
                pair_cnt = fx * (fx - 1)
            else:
                pair_cnt = fx * fy
            
            z = x + y
            if z in freq:
                ans += pair_cnt * freq[z]
    
    print(ans)

if __name__ == "__main__":
    solve()
```实现首先将数组压缩成频率图。 嵌套循环迭代值空间而不是索引空间，这是关键的减少。 的处理$x = y$case 确保有序索引对不会重用相同的索引。 的查找$z = x + y$是使用哈希映射的常数时间。 

一个微妙的点是循环是在有序对上进行的，而不是无序对上。 这是必要的，因为$(i, j)$和$(j, i)$是不同的有效三元组，并且两者必须单独计算。

 ## 边缘情况

 一种重要的边缘情况是所有元素都相同。 例如，$[1, 1, 1]$。 每对订购的$(i, j)$和$i \neq j$已计算，但总和为$2$，数组中不存在，因此正确答案是零。 该算法处理这个问题是因为$z = x + y$在频率图中从未找到。 

另一种边缘情况是重复值，其中存在有效和但来自相同的操作数。 在$[2, 2, 4]$，这对$(2, 2)$被算作$2 \cdot 1 = 2$有序索引对，每个索引对映射到两个选择$k$，总共产生四项贡献。 基于频率的配对公式确保索引不会被重复使用。 

最后一个微妙的情况是数组同时包含小值和大值，例如$[1, 1000000000000000000, 1000000000000000001]$。 该算法仍然有效，因为它仅依赖于总和的哈希查找，而不依赖于任何排序或范围假设，并且大整数在 Python 算术中自然处理。
