 ## 解决方案
 ## 问题理解

 我们给出了一系列应用于大小为稀疏数组的写入操作$n$，最初为空。 每个操作写入一个值$x$就位$i$。 不同的是，两个不同的系统对覆盖的解释不同。 一个系统拒绝覆盖已填充的位置，而另一个系统总是替换旧值。 

我们可以在执行之前删除一些操作。 删除后，两个系统都会处理剩余的命令，但会根据自己的覆盖规则进行处理。 我们希望生成的最终数组完全匹配：最终填充的每个位置都必须在两个系统中包含相同的值，并且两个系统都必须就填充哪些位置达成一致。 

任务是删除最少数量的操作，以便尽管覆盖语义不同，两种解释都会产生相同的最终状态。 

约束条件明确了关键难点。 操作次数最多为$2 \cdot 10^5$，因此任何成对比较操作或模拟子集决策的方法都太慢。 数组大小$n$可以大到$10^9$，这意味着我们无法存储每个位置的状态； 只有实际出现在操作中的位置才是重要的。 

一种简单的方法是尝试命令子集或模拟两个系统，同时选择要保留的操作。 这立即变成指数级的。 即使没有仔细排序的贪婪的每个位置重建也会失败，因为不同的值在同一索引上竞争，并且稍后覆盖会在两种解释之间交互。 

当同一位置接收到多个不同的值时，会出现微妙的边缘情况：

 输入：```
1 3
1 2
1 3
1 2
```如果我们尝试保留所有命令，两个系统会出现分歧，因为一个系统可能会拒绝覆盖，而另一个系统会接受覆盖，从而根据“坚持”的操作产生不同的最终值。 正确的答案需要有选择地删除命令，以便两种解释有效地“同意”哪个写入是每个位置的最后一个有意义的写入。 

## 方法

 关键的困难在于，每个索引的行为都是独立的，但前提是我们了解两个系统之间的全局一致性意味着什么。 

让我们首先考虑暴力。 我们可以尝试删除操作子集并准确模拟两个系统。 对于每个子集，我们按顺序应用命令，跟踪具有不同覆盖规则的两个数组。 处理后，我们比较结果。 这是可行的，因为它直接遵循定义，但速度慢得令人绝望。 有$2^q$子集，甚至评估一个子集成本$O(q)$，导致不可行的$O(q \cdot 2^q)$。 

我们需要了解哪些属性实际上破坏了一致性。 专注于单一指标$i$。 假设我们查看影响的所有操作$i$， 为了。 对于每个值$x$，只有一次事件最终在最终一致状态中“起作用”，因为任何早期的冲突写入都必须被删除或忽略。 

关键的洞察力是扭转观点。 不要考虑删除操作来强制达成一致，而是考虑必须保留哪些操作，以便两个系统就每个索引的最终“有效最后写入”达成一致。 仅当多个不同的值在同一指数上竞争时才会出现分歧。 在每个索引中，确保一致的唯一方法是选择在两种覆盖语义下都保持一致的写入子序列，这减少了保留一组精心选择的非冲突写入的情况。 

如果我们按索引对操作进行分组，则每个组都会变成一个值序列。 我们希望保留一个子序列，以便在应用时两个系统产生相同的最终值。 这意味着无论覆盖行为如何，每个索引的最后保留值都必须相同，因此我们实际上为每个索引选择一致的“最终代表写入”，并确保所有保留操作与其兼容。 

如果我们以相反的顺序处理操作，则最优结构会变得更加清晰。 当向后扫描时，我们决定写入是否是我们第一次在该索引处看到值。 如果是，我们可以保留它作为该职位的最终代表。 任何会以不同方式覆盖它的早期冲突写入都必须被删除。 

这变成了经典的“最后一次出现选择”逻辑：对于每个索引，只有每个值的最后一次出现才可能是相关的，并且在这些值中，我们选择决定最终状态的最新有效分配。 必须删除所有其他冲突操作。 

因此，问题简化为跟踪每个索引，我们已经承诺将哪些值保留为“最终候选者”，并将所有其他操作计为删除，除非它们从后面建立了第一个一致的分​​配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集 |$O(q \cdot 2^q)$|$O(q)$| 太慢了|
 | 使用上次查看的跟踪进行反向扫描 |$O(q)$|$O(q)$| 已接受 |

 ## 算法演练

 我们处理按索引分组的操作，但从最后开始在一次传递中实现，以便我们可以识别每个位置值对的最后一个有意义的写入。 

1. 从最后一个命令到第一个命令遍历操作。 这确保了当我们遇到一对时$(i, x)$，我们最后一次看到这个确切的分配可能很重要。 
2.维护字典`seen[i]`存储是否索引$i$已经接受了最终值。 如果没有，我们还会跟踪分配了哪个值。 
3.维护一套`used[i]`或全局标记是否为特定对的地图$(i, x)$已经考虑过了。 这可以防止对同一索引处同一值的多次出现进行计数。 
4. 对于每个操作$(i, x)$，如果索引$i$尚未分配最终值，我们接受此操作作为该索引和标记的定义写入$i$如指定的那样。 
5.如果索引$i$已分配，但当前值与所选的最终值不同，此操​​作不能在一致的解决方案中共存，并且必须被视为被忽略。 
6. 统计所有不被接受的对最终一致配置有贡献的操作； 这个数就是答案。 

关键思想是，当我们在向后扫描时第一次遇到索引时，我们实际上是在选择它的最终值。 任何后续的冲突操作（按原始顺序排列的较早的操作）都是无关紧要的，必须删除。 

### 为什么它有效

 一旦我们通过遇到第一个向后出现的索引来修复索引的最终值，该索引处的所有其他值要么在一种解释中覆盖它，要么在另一种解释中被忽略。 这种不匹配正是导致分歧的原因。 通过以相反的顺序提交第一个遇到的值，我们确保所有剩余的接受操作与每个索引的单个最终分配一致，从而消除了覆盖语义之间出现分歧的任何可能性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    ops = [tuple(map(int, input().split())) for _ in range(q)]
    
    assigned = {}
    used = set()
    removed = 0

    for i in range(q - 1, -1, -1):
        idx, val = ops[i]
        if idx not in assigned:
            assigned[idx] = val
        else:
            if assigned[idx] != val:
                removed += 1

    print(removed)

if __name__ == "__main__":
    solve()
```该代码读取所有操作并以相反的顺序处理它们。 字典`assigned`记录每个索引的最终选择值。 我们第一次看到反向索引是该索引的固定值。 以后在同一索引处遇到不同值的任何操作都将被视为必须忽略的操作。 

变量`used`在最终的简化解决方案中是不必要的，因为一旦分配了索引，我们只关心其值的一致性，而不关心相同值的多次出现。

 ## 边缘情况

 当所有操作都针对单个索引但替代值时，会出现微妙的边缘情况。 在这种情况下，只有前面遇到的最后一个值应该存活。 例如：```
1 4
1 1
1 2
1 3
1 4
```向后处理，我们首先分配 4 作为最终值。 每个较早的不同值都会变得无效，因此计为 3 次删除。 该算法可以正确处理此问题，因为第一次反向遭遇立即修复了最终状态。 

另一种情况是每个索引都出现一次。 由于不存在冲突，所以每个操作都被接受。 反向扫描为每个索引分配一次并且永远不会触发不匹配，从而产生零删除。
