 ## 解决方案
 ## 问题理解

 这里描述的程序采用一个整数数组，并在将其转换为垂直条形图之前执行简单的过滤步骤。 所有非正值都将被丢弃，其余值保持其原始顺序。 如果没有任何内容通过此过滤，该过程将立即失败。 否则，每个剩余值将成为网格中一列的高度，并且网格将这些高度可视化为从下到上的堆叠块。 

关键思想是最终输出不是任意的 ASCII 艺术。 它必须表示从某些正整数序列中绘制的直方图。 每一列对应过滤后数组的一个元素，每一列从下往上填充`#`恰好等于该值的行数。 上面的一切都是`.`。 

我们得到一个网格，并询问它是否可以通过这样的过程生成，如果可以，我们必须重建任何有效的最小长度的原始数组。 

约束很小，两个维度都达到 100，这表明 O(r·c) 或 O(r·c log c) 重建就足够了。 真正的困难不是性能，而是解释的正确性：必须根据隐式直方图的结构检查网格，该直方图具有在底部对齐的连续块的严格垂直列。 

一个天真的但常见的失败案例是误读底部对齐规则。 例如，像这样的列```
.#
#.
```不可能发生，因为`#`必须始终从下向上连续。 另一个微妙的失败是忘记了列是独立的：不要求高度排序或单调。 

## 方法

 暴力的视角是猜测长度为 c 的所有可能数组，每个条目在 0 到 r 之间，并检查它们的直方图是否与网格匹配。 即使我们忽略预处理步骤（删除非正值），这也已经产生$(r+1)^c$可能性，即使对于 c = 100 来说也是天文数字。 

一旦我们逐列查看网格，问题的结构就消除了所有歧义。 最终图像的每一列都唯一地确定了数组中必须存在的值，因为连续的高度`#`底部的单元格正是该值。 除了保留数组顺序之外，列之间没有交互。 

唯一剩下的复杂性是有效性：每列必须有一个连续的块`#`在底部，上面没有任何东西。 如果任何列违反了这一点，则任何数组都无法生成它。 一旦有效，重建的数组只是列高的列表。 

原始程序中的“清理”步骤仅删除非正值。 由于输出网格仅包含`#`和`.`，任何有效列都必须对应于严格的正整数，因此我们永远不需要显式重建删除的元素。 最小长度要求变得自动：每个有效列必须恰好贡献一个正数，并且没有理由引入额外的元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举| O((r+1)^c · r·c) | O((r+1)^c · r·c) | O(r·c) | 太慢了|
 | 柱重建| O(r·c) | O(c) | 已接受 |

 ## 算法演练

 我们将网格解释为 c 个独立的垂直列。 

1. 对于每一列 j，我们计算有多少个连续的`#`从底行开始向上出现。 此计数是可以生成此列的条形的唯一可能高度。 任何高于该块的偏差都会立即使该列失效。 
2. 向上扫描时，如果遇到`#`在已经看到一个之后`.`，该柱在结构上是不可能的。 这是因为直方图定义需要所有`#`单元格从底部形成连续的后缀。 
3. 我们将计算出的每一列的高度存储在一个数组中。 如果某列为零`#`，它的高度将为零，这在最终重建的数组中是不允许的，因为清理后仅保留正整数。 然而，这样的列只要是完全空的就仍然可以接受； 它只是意味着它会在预处理过程中被删除，但由于输出需要最小的正数组来生成网格，我们将其视为无效，除非我们仔细重新解释：事实上，一列为零`#`表示高度为 0，但由于清理后的数组删除了非正值，因此根本不会出现这样的列。 因此，任何全点列都会使答案变得不可能。 
4. 处理完所有列后，如果所有列都是正数且有效，则输出高度数组。 

### 为什么它有效

 输出网格中的每一列完全由单个整数高度确定。 直方图构造在列之间没有耦合，因此当且仅当每列都是后缀时网格才有效`#`具有一定的正长度。 因此，重建是单射的：每列恰好有一个可能的值，并且任何有效的解决方案都必须与这些值匹配。 任何违反连续性或存在孤立性的行为`#`cells 与底部对齐堆叠的定义相矛盾，因此拒绝是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

r, c = map(int, input().split())
grid = [input().strip() for _ in range(r)]

heights = []

for col in range(c):
    h = 0
    seen_dot = False

    for row in range(r - 1, -1, -1):
        if grid[row][col] == '#':
            if seen_dot:
                print("No")
                sys.exit(0)
            h += 1
        else:
            seen_dot = True

    if h == 0:
        print("No")
        sys.exit(0)

    heights.append(h)

print("Yes")
print(len(heights))
print(*heights)
```该解决方案直接对按列重建进行编码。 选择向下扫描是因为直方图的定义是底部对齐的，因此从底部开始计数可以避免额外的变换。 

这`seen_dot`标志强制连续性：一旦我们离开`#`地区，我们决不能再看到另一个地区`#`。 这是区分有效直方图和任意模式的关键结构约束。 

支票`h == 0`确保符合最终清理后的数组仅包含正整数的要求，这意味着每个幸存的列必须至少贡献一个`#`。 

## 工作示例

 考虑第一个样本：```
..#
#.#
#.#
###
```我们逐列处理。 

| 专栏 | 自下而上扫描 | 看到断点了吗？ | 身高|
 | --- | --- | --- | --- |
 | 0 | #.#. | 没有| 3 |
 | 1 | ###。 | 没有| 1 |
 | 2 | #### | 没有| 4 |

 重构后的数组为`[3, 1, 4]`。 

这证实了有效列是独立的并且完全由后缀计数确定。 

现在考虑一个无效的网格：```
..#
###
#.#
###
```第 1 列（中间列）会出现问题，因为自下而上的扫描会产生`# # . #`，意思是遇到一个点后，会重新出现一个散列。 这违反了所需的连续结构，因此算法立即拒绝。 

这表明主要失效模式不是高度不匹配，而是柱内结构不一致。

 ## 边缘情况

 具有一列所有点的网格会立即失败，因为重建的高度变为零。 例如：```
2 2
..
..
```在处理过程中，两列的高度均为 0，因此算法输出`No`。 这与清理后数组将为空的事实相符，这是明确禁止的。 

一个列，其中`#`出现在上面`.`也被拒绝。 例如：```
3 1
#
.
#
```扫描自下而上的遭遇`#`， 然后`.`， 然后`#`，触发无效状态标志。 这捕获了底部对齐直方图的核心结构约束。 

完全有效的高列，例如：```
5 1
.
.
#
#
#
```产生高度 3，并且不会出现不一致的情况。 算法正确重建`[3]`，确认带有前导点的稀疏网格是自然处理的。
