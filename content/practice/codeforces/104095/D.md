 ## 解决方案
 ## 问题理解

 我们有一行$n$植物，每个植物都以相同的高度开始$h$。 对于每个植物，我们可以保持其不变或将其削减到严格小于的任何整数高度$h$。 在选择所有植物的最终高度后，我们必须满足以下序列$n-1$相邻植物之间的严格比较：每次比较要么“左比右小”，要么“左比右大”。 

任务是计算可以形成多少个不同的最终高度数组来满足所有这些不等式，其中如果至少一个位置具有不同的最终高度，则两个数组被认为是不同的。 答案取模$10^9+7$。 

一个关键的观察直接来自操作定义：每个位置只能取范围内的值$[1, h]$，并且我们可以独立地自由选择该范围内的任何值，除非邻接约束耦合了这些选择。 所以这从根本上来说是一个整数序列的约束计数问题。 

限制条件$n \le 3000$和$h \le 10^6$立即排除任何迭代每个位置的实际高度值的方法。 任何尝试显式枚举每个边的整个值范围内的高度或过渡的解决方案都会太慢。 我们需要一个公式，其中依赖于$h$至多是线性或对数的。 

一个微妙的边缘情况是$h = 1$。 在这种情况下，位置不能减少，因此每个元素都被迫恰好为 1。当且仅当所有约束都与相等值一致时，唯一有效的配置才存在，这是不可能的，因为所有比较都是严格的。 所以当$n > 1$和$h = 1$。 

另一个重要的边缘情况是完全单调的约束链，例如全是“<”。 在这种情况下，有效序列对应于严格递增的序列，其边界为$h$，数量仍然可以很多，但必须遵守严格的上限。 

## 方法

 蛮力方法将尝试所有高度分配$[1, h]$对于每个$n$位置，然后检查每个分配是否满足所有不等式。 这已经给出了$h^n$的可能性，即使对于微小的人来说也是完全不可行的$n$。 

我们需要压缩状态空间。 关键的观察是，重要的不是绝对值，而是它们由不平等链引起的相对顺序。 由于所有约束都是邻居之间的严格比较，因此序列取决于我们如何在本地对元素进行“排名”，然后分配与这些排名一致的实际值。 

如果我们固定一个相对模式，这意味着对于每个位置，我们决定其值与之前的值进行比较，实际的数字分配对应于沿着某些段选择严格增加的不同值序列。 每个片段的行为就像一个单调的运行。 

标准简化是将数组视为根据方向变化划分为单调块。 在每个块内，约束在固定方向上强制执行严格的单调性，而在块之间，方向会翻转。 那么问题就变成了计算有多少种赋值方式$[1, h]$到具有交替单调约束的序列。 

这可以使用动态规划来解决，其中我们跟踪每个前缀有多少种方式结束于给定的“排名结构”，但我们通过在值空间上使用前缀和来避免迭代高度。 每个转换都会成为前缀或后缀总和，具体取决于我们是向上还是向下。 

关键结构是，在每个位置，我们只需要允许范围内的累积计数，因此我们可以在位置和可能的最终高度上维护 DP，范围转换为线性$h$，但使用前缀和进行优化，以便每个转换$O(1)$。 

这将问题从指数枚举简化为$O(nh)$动态规划，这是可以接受的，因为$n \le 3000$和$h \le 10^6$，但我们还进一步压缩 DP：由于转换仅依赖于前一行前缀和，因此我们只存储两个大小的数组$h$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(h^n)$|$O(n)$| 太慢了|
 | 具有前缀优化的 DP |$O(nh)$|$O(h)$| 已接受 |

 ## 算法演练

 我们定义一个 DP 数组，其中$dp[i][x]$是为第一个指定高度的有效方法的数量$i$位置这样的位置$i$有精确的高度$x$。 由于我们只是从$i-1$到$i$，我们可以将其压缩为两个数组。 

1. 初始化$dp[1][x] = 1$为所有人$1 \le x \le h$，因为第一棵植物可以独立地占据任何高度。 
2. 对于之间的每个约束$i-1$和$i$，我们根据关系是“<”还是“>”来更新一个新的DP数组。 
3. 如果约束条件是“<”，那么对于每个值$x$在位置$i$，我们必须有$dp[i][x] = \sum_{y < x} dp[i-1][y]$。 这反映出先前的高度必须严格小于。 
4. 如果约束是“>”，那么对于每个值$x$，我们必须有$dp[i][x] = \sum_{y > x} dp[i-1][y]$，这意味着我们将之前所有较大的高度相加。 
5. 为了有效地计算这些和，我们构建先前 DP 数组的前缀和。 那么“<”查询就变成了前缀查找，而“>”查询就变成了总和减去前缀。 
6. 处理完所有位置后，答案就是所有位置的总和$dp[n][x]$为了$1 \le x \le h$。 

### 为什么它有效

 DP 状态完全捕获所有有效的部分分配，因为任何有效的前缀分配都由最后一个高度唯一表征。 转换对每个边执行一次邻接约束，并且每个有效序列仅贡献一条通过 DP 的路径。 前缀和变换不会改变语义，它只是有效地重新表达范围和。 由于每个扩展步骤都在本地保留正确性并覆盖所有有效的延续，因此最终的总和仅对所有有效序列进行一次计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, h = map(int, input().split())
    s = input().strip()

    if h == 1:
        # only one possible array, but strict constraints make it impossible for n>1
        return 1 if n == 1 else 0

    dp = [1] * (h + 1)

    for i in range(n - 1):
        ndp = [0] * (h + 1)
        pref = [0] * (h + 1)

        for v in range(1, h + 1):
            pref[v] = (pref[v - 1] + dp[v]) % MOD

        if s[i] == '<':
            for x in range(1, h + 1):
                ndp[x] = pref[x - 1]
        else:
            total = pref[h]
            for x in range(1, h + 1):
                ndp[x] = (total - pref[x] + MOD) % MOD

        dp = ndp

    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```实现直接遵循 DP 定义。 前缀数组在每一步都会重新计算，以实现恒定时间范围总和。 “<”转换使用前缀最多$x-1$，而“>”转换使用总减前缀$x$，小心地保持严格的不平等。 

唯一微妙的界限是确保严格性：对于“<”，我们排除$x$本身，因此$pref[x-1]$。 对于“>”我们排除$x$同样，因此减去$pref[x]$。

```我们从以下开始：

 转换 1 是“<”：

 | x| 前缀 | 国家民主党|
 | --- | --- | --- |
 | 1 | 0 | 0 |

 | 3 | 2 | 2 |

 所以dp变成[0,1,2]。 

下一个转换是“>”：

 | x| 前缀 | 总计 | 国家民主党|
 | --- | --- | --- | --- |
 | 1 | 0 | 3 | 3 |

这符合这样的想法：只有相对顺序才重要，并且可行的分配对应于一致的严格链。

## 测试用例```python
import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, h = map(int, sys.stdin.readline().split())
    s = sys.stdin.readline().strip()

    if h == 1:
        return str(1 if n == 1 else 0)

    dp = [1] * (h + 1)

    for i in range(n - 1):
        ndp = [0] * (h + 1)
        pref = [0] * (h + 1)

        for v in range(1, h + 1):
            pref[v] = (pref[v - 1] + dp[v]) % MOD

        if s[i] == '<':
            for x in range(1, h + 1):
                ndp[x] = pref[x - 1]
        else:
            total = pref[h]
            for x in range(1, h + 1):
                ndp[x] = (total - pref[x] + MOD) % MOD

        dp = ndp

    return str(sum(dp) % MOD)

# provided sample
assert run("3 3\n<>\n") == "5", "sample 1"

# minimum n
assert run("2 2\n<\n") == "1", "two elements increasing"

# impossible strict chain
assert run("4 2\n<<<\n") == "0", "insufficient height"

# all decreasing
assert run("3 3\n>>\n") == "5", "symmetric case"

# h = 1 edge case
assert run("3 1\n<<\n") == "0", "h=1 forces impossibility"

 | 4 2 <<< | | 0 | 严格增长不可行|
 | 3 3 >> | 5 | 对称递减情况 |
 | 3 1 << | 0 | 退化高度限制|

 ## 边缘情况

 当$h = 1$，每个位置都强制为 1。算法正确返回 0，除非$n = 1$，因为在严格的不平等条件下，所有 DP 转换都会崩溃为零。 

对于像“<<<…”这样的完全单调链，DP 会迅速崩溃，因为前缀和最终在超出可行范围的情况下变为零，这与严格递增序列超出可用不同值的组合不可能性相匹配。 

对于像“<><><”这样的交替模式，DP 保持多个活动状态，并且前缀-后缀转换保持对称性而不丢失有效配置，从而确认每个有效序列在 DP 演化过程中被精确计数一次。
