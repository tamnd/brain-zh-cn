 ## 解决方案
 ## 问题理解

 每个学生要么只竞争一个职位，要么他们对某一特定职位都不重要。 对于每个职位，我们必须查看所有申请该职位的学生，并选择得票数最高的学生。 如果多个学生获得相同的最大票数，则通过选择最小的学生指数来解决平局。 

输入给出了一份学生列表，其中每个学生声明一个目标位置和票数。 任务是重建每个位置$1$到$m$，哪个学生在应用“最大票数，然后最小指数”规则后赢得该位置。 

界限非常小：$n \le 51$和$m \le 12$。 这消除了对效率的任何担忧。 甚至一个$O(nm)$或者$O(n^2)$模拟速度非常快。 唯一真正的要求是分组和打破平局的正确性。 

最常见的失败案例是忘记打破平局顺序或未能按位置正确对学生进行分组。 例如，如果两个学生以相同的票数瞄准相同的位置，则即使所有值都已处理，选择较晚的输入而不是较小的索引也会产生错误的答案。 

另一个微妙的问题是假设仓位是独立的，但由于共享变量或未重置每个仓位最大值而意外地混合了仓位之间的索引。 

## 方法

 问题的结构已经是最优的方法了。 每个位置都是独立的，因此自然的解决方案是将所有候选者按其选择的位置进行分组并计算一个简单的最大值。 

对于每个职位，强力解释都会扫描所有学生并选出最佳候选人。 这是可行的，因为每个位置决策都是独立的并且只需要线性扫描。 成本是$O(nm)$操作，因为对于每个$m$我们检查所有职位$n$学生。 在给定的限制下，这已经是最小且高效的了。 

关键的观察是位置之间不存在相互作用。 一名学生恰好属于一个组，因此我们不需要全局排序或匹配。 整个问题简化为字典键为的重复最大选择$(t_i, -i)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个位置的强力扫描 |$O(nm)$|$O(1)$额外 | 已接受 |
 | 团体+单程|$O(n + m)$|$O(m)$| 已接受 |

 两者在实践中实际上是相同的； 分组版本只是使结构更加清晰。 

## 算法演练

 1. 创建数组`best_id`尺寸的$m$初始化为$0$，代表每个位置的当前获胜者。 还维护`best_score`初始化为$0$对于每个位置。 此设置对每个位置始终存储其当前最佳候选的不变量进行编码。 
2. 阅读每个学生$i$从$1$到$n$，选择位置$c_i$和选票$t_i$。 
3. 对于职位$c_i$， 比较$t_i$当前最好成绩存储在`best_score[c_i]`。 
4.如果$t_i$大于当前最好成绩，将两者替换`best_score[c_i]`和`best_id[c_i]`和$t_i$和$i$。 这确保了该职位保留迄今为止得票最高的候选人。 
5. 如果$t_i$等于当前最好成绩，比较学生指数。 如果$i$小于存储的最佳索引，则替换存储的获胜者。 这强制执行打破平局的规则。 
6.处理完所有学生后，输出`best_id[1]`通过`best_id[m]`。 

### 为什么它有效

 在处理过程中的任何时候，每个位置都会根据字典顺序存储迄今为止该位置的所有学生中的最佳候选者$(t_i, -i)$。 每个新学生要么完全更好，要么完全更差，要么在选票上平分秋色，在平局的情况下，只有最小的指数幸存下来。 由于每个学生只被处理一次并且比较是单调更新，因此最终存储的值必须是每个位置的全局最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    best_score = [0] * (m + 1)
    best_id = [0] * (m + 1)

    for i in range(1, n + 1):
        c, t = map(int, input().split())
        if t > best_score[c]:
            best_score[c] = t
            best_id[c] = i
        elif t == best_score[c] and i < best_id[c]:
            best_id[c] = i

    print(*best_id[1:])

if __name__ == "__main__":
    solve()
```该解决方案维护两个按位置索引的数组。 一个存储迄今为止看到的最佳投票数，另一个存储相应的学生索引。 更新逻辑直接对选择规则进行编码，最终输出只是按顺序列出每个位置的获胜者。 

一个微妙的点是初始化：设置`best_score`到$0$有效，因为票数保证至少为$1$。 另一个细节是`best_id`开始于$0$，这是有效的，因为任何真实的学生指数至少是$1$，因此第一个有效候选者总是会覆盖它。

 ## 边缘情况

 一个关键的边缘情况是多个学生以相同的选票竞争同一职位。 该算法通过仅在投票数相等时比较索引来处理此问题，确保保留最小索引。 

另一种极端情况是某个职位仅接收一名候选人。 初始化为零可确保第一个候选者始终成为获胜者。 

最后一个极端情况是不同职位的候选者按输入顺序交错。 由于每次更新只涉及自己的位置索引，因此位置之间不会发生干扰，从而自动保持正确性。
