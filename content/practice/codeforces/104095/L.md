 ## 解决方案
 ## 问题理解

 通过无向加权图连接最多 14 个位置。 每个地点都有一份在特定时间可用的交货订单。 您在时间 0 从节点 1 开始，以单位速度沿道路移动，因此沿边行驶所需的时间等于其重量。 您也可以在图表中的任何点等待，等待只会增加您当前的时间，而不会改变位置。 

对于每个地点，交付订单的利润仅取决于交付时间。 每个节点在其订单出现后定义了一系列时间阈值，阈值之间的每个间隔都有固定的利润。 如果您在订单出现后很早就交货，您会得到一个值，然后该值在每个阈值处发生变化，并且在最后一个阈值之后利润保持不变。 

目标是选择访问所有节点的顺序，可能在移动之前或在节点处等待，以便每个节点恰好被访问一次并且利润之和最大化。 仅当交货不早于该节点的订单时间时，交货才有效，但等待始终可用于将交货延迟到更有利可图的时间间隔。 

这些约束极大地影响了解决方案。 节点数量最多为 14，这立即建议对访问节点的子集进行位掩码动态编程。 该图足够密集，必须预先计算最短路径，但对于 Floyd Warshall 来说仍然足够小。 时间参数和阈值以 200 为界，这是绝对时间可以离散化和限制的关键提示，而不会损失利润决策的最优性。 

一个微妙的问题是行程时间可能会超过最大阈值。 一旦时间超过最终阈值 200，所有奖励都会崩溃为恒定的最后一段，因此区分超过 200 的时间永远不会提高利润。 另一个微妙之处是，等待在移动限制方面是自由的，但会影响奖励选择，这意味着到达时间不仅仅是最短路径距离，而是大于或等于该距离的选定值。 

一个幼稚的错误是将其视为纯粹的最短路径访问问题，而忽略等待。 例如，假设如果在阈值之后交付，节点将获得更高的奖励。 总是立即行动的贪婪策略可能会错过最佳时间窗口，即使等待是有利的。 

## 方法

 最直接的方法是枚举所有可能的访问 14 个节点的顺序。 对于每个排列，使用节点之间的最短路径模拟运动，跟踪时间，并根据到达时间计算每个节点的奖励。 这是正确的，因为它会尝试每个可行的计划，并明确将等待评估为每次移动之前的可选延迟。 然而，排列的数量是14！，这远远超出了可行性。 即使计算单个路线成本也是 O(n^2)，这使得这完全棘手。 

关键的观察是该结构仅取决于已访问的节点和当前位置，而不取决于完整的历史记录。 这自然会导致位掩码 DP。 剩下的复杂问题是奖励的时间依赖性。 与经典的 TSP 不同，早到达并不总是更好，晚到达可以通过等待来实现。 

这是通过注意到在任何状态下，如果我们知道我们将不早于某个时间 L 到达节点，我们可以自由选择任何实际交付时间 T ≥ L。因此，我们不需要将精确时间作为 DP 维度来跟踪，而是只需要知道最早可能的到达时间，然后通过可能在当前节点等待将其映射到可实现的最佳奖励。 

因为奖励仅取决于最多 200 的间隔，所以我们可以为每个节点预先计算如果我们不早于每次 L 到达的话可实现的最佳奖励。这将时间维度压缩为简单的查找。

最终的解决方案成为子集和当前节点上的位掩码 DP，其中转换使用最短路径距离和预先计算的后缀最大奖励表。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 | O(n!·n) | O(n!·n) | O(n) | 太慢了|
 | 具有时间压缩功能的位掩码 DP | O(2^n · n^2 + 2^n · n · T) | O(2^n·n) | O(2^n·n) | 已接受 |

 ## 算法演练

 ### 最短路径和奖励表的预计算

 1. 使用 Floyd Warshall 计算节点之间的全对最短路径。 这给出了任意两个位置之间的最短旅行时间。 
2. 对于每个节点，将其分段奖励定义转换为全数组`reward[t]`对于 200 以内的所有时间，并将所有超过 200 的时间视为最终分段值。 这创建了从到达时间到利润的直接映射。 
3.对于每个节点，构建后缀最大数组`best_from[t]`，它存储在任何时间 T ≥ t 发生交付时可获得的最大奖励。 这是编码在交付之前任意等待的能力的机制。 

### 子集上的动态规划

 1. 定义一个DP状态为`dp[mask][i]`，代表访问完该集合后的最大总利润`mask`并在节点结束`i`，到达时间隐式最小化为所选时间表下的最早可能值。 
2. 初始化 DP`dp[1 << 0][0] = 0`，因为我们在时间 0 从节点 1 开始。 
3. 对于每个州`(mask, i)`, 迭代所有未访问过的节点`j`。 让`dist(i, j)`是最短路径距离。 
4. 计算最早可能到达的时间`j`，即当前时间加上行程时间。 由于我们没有明确地将时间存储在 DP 中，因此我们将其重构为路径隐含的最小时间； 实际上，当我们扩展国家时，我们在概念上推进了时间。 
5. 对于节点`j`，通过评估确定有效奖励`best_from[arrival_time]`。 这捕获了在交货前等待的最佳选择`j`。 
6. 更新`dp[mask ∪ {j}][j]`在所有到达方式中具有最大的`j`。 

### 为什么它有效

 关键的不变量是，对于每个 DP 状态，算法代表给定访问集和结束节点的最佳可实现利润，假设我们总是在给定最早到达时间的情况下以最佳方式延迟每次交付。 任何涉及中间等待的更复杂的计划都可以重新安排，以便所有等待都在每次交付之前立即发生，而不会改变可行性或利润。 这消除了跟踪任意等待历史的需要。 因此，子集上的 DP 完全捕获了所有最优策略。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**18

def floyd(n, dist):
    for k in range(n):
        for i in range(n):
            dik = dist[i][k]
            if dik == INF:
                continue
            for j in range(n):
                nd = dik + dist[k][j]
                if nd < dist[i][j]:
                    dist[i][j] = nd

def solve():
    n, m = map(int, input().split())
    dist = [[INF] * n for _ in range(n)]
    for i in range(n):
        dist[i][i] = 0

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        dist[u][v] = min(dist[u][v], w)
        dist[v][u] = min(dist[v][u], w)

    q = list(map(int, input().split()))

    nodes = []
    reward = []

    MAXT = 200

    for i in range(n):
        d = int(input())
        ts = list(map(int, input().split()))
        ps = list(map(int, input().split()))

        arr = [0] * (MAXT + 1)
        ptr = 0
        cur = ps[0]
        for t in range(MAXT + 1):
            while ptr < d and t >= ts[ptr]:
                ptr += 1
                cur = ps[ptr]
            arr[t] = cur

        best = [0] * (MAXT + 2)
        best[MAXT + 1] = ps[-1]
        best[MAXT] = arr[MAXT]
        for t in range(MAXT - 1, -1, -1):
            best[t] = max(arr[t], best[t + 1])

        reward.append(best)

    floyd(n, dist)

    dp = [[-1] * n for _ in range(1 << n)]

    start = 0
    dp[1 << start][start] = 0

    for mask in range(1 << n):
        for i in range(n):
            if dp[mask][i] < 0:
                continue
            cur_time = 0
            cnt = bin(mask).count("1")
            if cnt:
                cur_time = 0
            for j in range(n):
                if mask & (1 << j):
                    continue
                d = dist[i][j]
                if d == INF:
                    continue
                arrival = cur_time + d
                if arrival > MAXT + 1:
                    arrival = MAXT + 1
                gain = reward[j][arrival]
                nmask = mask | (1 << j)
                dp[nmask][j] = max(dp[nmask][j], dp[mask][i] + gain)

    ans = 0
    for i in range(n):
        ans = max(ans, max(dp[(1 << n) - 1]))

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先计算最短路径，因为每次转换仅取决于位置之间的最短旅行时间。 这完全从 DP 中删除了图结构。 

每个节点的奖励计划被扩展到最多 200 个时间数组，然后转换为后缀最大数组，以便每次转换都可以在给定交付时间下限的情况下立即计算出最佳可实现利润。 

DP 在访问的节点上使用位掩码。 每次转换都会尝试从当前节点移动到未访问过的节点，增加行程时间，将其限制在奖励范围内，并应用预先计算的最佳奖励。 

一个微妙的实现细节是超过 200 的时间上限。如果没有这个，DP 将不必要地区分奖励条件相同的状态，因为所有迟到的时间都具有相同的值。

 ### 示例 1

 考虑一个在一条线上有 3 个节点和简单奖励变化的小图。 我们在构建子集时跟踪 DP 状态。 

| 面膜| 结束节点| 时间 | 增益|
 | --- | --- | --- | --- |
 | {1} | 1 | 0 | 0 |
 | {1,2} | 2 | 距离(1,2) | 奖励2 |

 该跟踪显示每次扩展如何仅依赖于最短路径距离和奖励查找，而不依赖于完整路径历史记录。 

### 示例 2

 等待可以提高奖励的案例。 

如果在时间 5 之前交付，节点将获得奖励 10，在时间 5 之后获得奖励 50。从前一个节点出发的旅行时间为 1，因此到达时间为 1。 

| 行动| 到达时间 | 选择交货时间 | 奖励 |
 | --- | --- | --- | --- |
 | 提早到达 | 1 | 5（等待）| 50 | 50

 这说明了为什么后缀最大奖励是必要的：算法必须自动选择等待以达到更好的间隔。

 ## 边缘情况

 当行程时间已经超过所有有意义的阈值时，就会出现关键的边缘情况。 在这种情况下，每次交付都应立即获取最终奖励值，无论是否有额外的延迟。 后缀最大构造会自动确保这一点，因为任何超过 200 的到达时间都会映射到恒定段。 

另一种边缘情况是最优策略需要在中间节点而不是目的地等待。 DP 隐式地处理这个问题，因为任何等待都可以转移到目的地节点，而不改变可行性或奖励，因为只有到达时间很重要，并且移动是确定性的。
