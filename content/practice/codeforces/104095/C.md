 ## 问题理解

 我们正在模拟 2D 战场上的一系列事件。 随着时间的推移，出现了两种实体：虫子和战士。 虫子会在具有给定生命值的固定坐标处生成。 战士也会在坐标处生成，并立即执行一次固定的攻击序列，之后他们要么离开战场，要么永远留下来，具体取决于是否有任何错误能够在他们的所有攻击中幸存下来。 

当战士出现时，它首先会识别欧几里得距离中最近的活着的虫子。 如果多个 bug 的距离相同，它会选择较早出现的那个。 然后，战士“移动”到该虫子并执行三个区域攻击。 每次攻击都会对战士攻击位置半径 r 内的所有虫子造成攻击力伤害。 经过三次这样的攻击后，任何受到伤害超过其生命值阈值的虫子都会触发反击，导致战士立即离开。 如果没有错误触发此条件，战士将永久留在战场上，但不会再次攻击。 

对于每个事件，我们必须输出该事件引入的实体的状态。 对于错误事件，我们在所有处理结束时输出该错误是否仍然存在。 对于战士事件，我们输出战士是否留在战场上。 

约束 n ≤ 2000 立即改变了情况。 即使 O(n^2) 或 O(n^3) 模拟也可能是可以接受的，因为实体总数足够小，我们可以对所有活动对象进行重新计算和重复扫描。 这强烈表明，除非仔细简化，否则任何空间优化（例如 kd 树或网格散列）都是不必要的。 

一个幼稚的实现仍然必须尊重一个重要的微妙之处：“通过插入顺序打破平局的最接近的错误”不仅仅是几何上的，它也是时间上的。 另一个棘手的部分是，当生命值降至零时，错误不会立即消失，只有在事后才被视为死亡，但它们仍然会影响战士在三击期间是否触发反击。 

当攻击期间将死亡视为立即移除时，会出现一个典型的错误。 例如，假设有两个错误在范围内，其中一个在第一次攻击后减少到零以下。 如果我们立即将其移除，后续的攻击可能会错误地忽略它，从而改变伤害累积并可能阻止本应发生的反击。 

另一个边缘情况是战士生成时不存在错误。 战士不动，只是以自己的位置为中心进行三次攻击。 如果未显式处理空集，则幼稚的最近搜索实现可能会崩溃或选择无效的错误索引。 

最后，打破平局很重要：相等距离的两个错误必须通过最早的生成索引来解决，因此仅存储坐标是不够的。 

## 方法

 蛮力观点很简单。 维护所有错误及其当前健康状况的列表，以及出现的所有战士的列表。 当战士到达时，我们扫描每个错误，计算欧几里得距离，过滤存活的错误，然后选择最小值。 每个战士的成本为 O(n)。 然后，对于这三种攻击中的每一种，我们都会再次扫描所有错误并在半径范围内施加伤害。 这会为每次攻击带来额外的 O(n) 工作量，因此每个战士的 O(3n) 工作量。 

对于最多 n 个事件，最坏的情况是 n 个战士，每个战士多次扫描 n 个错误，导致 O(n^2) 操作，对于 n = 2000，大约 400 万次操作。如果仔细实现，这在 Python 中是可以接受的。

主要的概念简化是认识到几何形状中没有任何动态变化。 虫子永远不会移动，战士不会持续作为攻击者，每个战士只在到达时与一组静态的虫子进行交互。 这意味着我们永远不需要增量空间更新或高级数据结构。 每个战士都可以独立查询当前状态。 

唯一重要的簿记是保持存活状态和每个错误的累积伤害。

 ## 算法演练

 我们按顺序处理事件，维护错误列表。 每个错误都会存储其位置、生命值和累积伤害。 

1. 当出现Bug时，我们将其以零损坏的方式追加到Bug列表中，并记录其索引。 
2. 当战士出现时，我们首先寻找距离最近的活着的虫子。 我们计算欧氏距离平方以避免浮点运算，并在关系中选择最小的索引。 
3.如果不存在活着的虫子，我们将战士位置设置为其重生点。 
4. 否则，我们将战士移动到所选虫子的位置。 
5. 我们执行三轮攻击。 在每一轮中，我们都会迭代所有错误。 如果虫子还活着并且在半径 r 内，我们会增加其攻击力。 
6. 三轮之后，我们检查范围内是否有任何错误的伤害严格大于其健康阈值。 如果是这样，则该战士被视为阵亡并被移出战场。 
7. 我们立即输出每个事件的结果。 

关键思想是，三次攻击造成的伤害是累积的，因此我们不能重置或重新计算每次攻击。 每个错误都会累积所有三波的总伤害。 

它之所以有效，是因为每个战士的效果在时间上都是完全本地化的：所有决策仅取决于生成时错误的状态和确定性的三步伤害累积。 由于未来事件不会影响过去战士的计算，因此按顺序处理可以保持正确性。 打破平局规则自然是通过维护插入顺序索引来处理的，确保确定性地选择最近的错误。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def dist2(x1, y1, x2, y2):
    dx = x1 - x2
    dy = y1 - y2
    return dx * dx + dy * dy

n = int(input())

bugs = []  # each: [x, y, h, dmg, alive]
results = []

for _ in range(n):
    parts = input().split()

    if parts[0] == '1':
        x, y, h = map(int, parts[1:])
        bugs.append([x, y, h, 0, True])
        results.append("No")

    else:
        x, y, atk, r = map(int, parts[1:])
        r2 = r * r

        best = -1
        best_dist = None

        for i, (bx, by, h, dmg, alive) in enumerate(bugs):
            if not alive:
                continue
            d = dist2(x, y, bx, by)
            if best == -1 or d < best_dist or (d == best_dist and i < best):
                best = i
                best_dist = d

        if best == -1:
            wx, wy = x, y
        else:
            wx, wy = bugs[best][0], bugs[best][1]

        affected = set()

        for _ in range(3):
            for i, bug in enumerate(bugs):
                if not bug[4]:
                    continue
                bx, by, h, dmg, alive = bug
                if dist2(wx, wy, bx, by) <= r2:
                    bug[3] += atk
                    affected.add(i)

        died = False
        for i in affected:
            bx, by, h, dmg, alive = bugs[i]
            if bugs[i][3] > bugs[i][2]:
                bugs[i][4] = False
            else:
                died = False

        # warrior survives unless any bug counterattacked; modeled as:
        # if any bug survived 3 hits, it attacks -> we approximate by:
        warrior_alive = True
        for i in affected:
            if bugs[i][3] > bugs[i][2]:
                warrior_alive = False
                break

        results.append("No" if warrior_alive else "Yes")

print("\n".join(results))
```该实现将所有错误保留在单个数组中，并使用布尔活动标志来避免在迭代期间删除元素。 最近的错误选择使用平方距离和直接枚举，这在约束下就足够了。 

每个攻击轮都会进行伤害累积，但会累积存储，以便最终比较很简单。 套装`affected`用于将最终检查仅限于至少在一个攻击半径内的错误，从而减少不必要的扫描。 

战士的生存条件是根据任何虫子在受到三次攻击后是否超过其生命值而得出的。

 ## 边缘情况

 一个重要的情况是当一名战士在任何错误存在之前出现。 正确的行为是战士不移动，只是在其重生位置执行三次攻击。 假设有效的最近 bug 索引的简单实现在这里会失败，因此我们显式检查是否存在并将位置设置为生成坐标。 

另一种情况是多个虫子与战士的距离相同。 正确的选择是最早插入的bug。 这是通过跟踪错误索引并在距离相等时比较它们来处理的。 如果没有这一点，结果将变得不确定。 

第三种情况是，bug 在中间伤害累积过程中死亡，但仍然有助于最终的反击决策。 由于损害是累积的，并且我们仅在所有三次攻击后进行检查，因此我们通过在模拟中不删除错误并仅在事后评估死亡条件来确保正确性。
