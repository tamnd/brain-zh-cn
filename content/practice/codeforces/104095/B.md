 ## 解决方案
 ## 问题理解

 我们给出了一个包含 n 集的连续过程，以及初始观众规模 m。 每集可能会也可能不会投放广告。 如果在第 i 集中投放广告，则每个当前观众都会贡献 pi 单位的利润，然后在下一集之前通过 di 划分观众数量，从而缩小观众数量。 如果不投放广告，则不会获得任何收益，受众也保持不变。 

关键的困难在于决策是跨时间耦合的。 我们是否提前做广告会影响稍后留下的观众数量，而跳过广告可以为未来的剧集保留观众规模。 任务是选择剧集的子集以使总收入最大化。 

约束 n、m ≤ 10^5 和 pi 高达 10^6 意味着尝试所有子集的任何方法都是不可能的，因为这将是 2^n 状态。 即使 O(n^2) 也太大了。 我们被迫走向线性或接近线性的动态过程，其中每个状态转换都受到仔细控制。 

当一个人试图贪婪地独立挑选所有有利可图的片​​段时，就会出现一种微妙的失败案例。 例如，考虑 m = 10，两集：

 第 1 集：p1 = 100，d1 = 10

 第 2 集：p2 = 1，d2 = 1

 如果我们两者都做广告，第 1 集产生 1000，观众变为 1，第 2 集产生 1。总数为 1001。如果我们跳过第 1 集而只播放第 2 集，我们将得到 10。仅基于 pi 的天真贪婪选择将完全失败。 通过减少受众而产生的耦合意味着地方决策不是独立的。 

另一个失败案例是认为如果广告能带来正利润，我们就必须接受它。 由于 di 可能很大，单个早期广告可能会破坏未来的收入潜力，从而使整体情况变得更糟。 

## 方法

 蛮力视图是模拟情节的所有子集。 对于每个子集，我们按顺序处理剧集，跟踪当前观众，应用乘法和除法，并累积奖励。 这是正确的，因为它完全尊重过程，但它需要检查 2^n 个子集，并且每次模拟成本为 O(n)，给出 O(n·2^n)，这是不可行的。 

关键的观察是，一旦我们确定了所选的剧集集，观众的演变就是确定性的。 每个决策仅通过当前受众值影响未来状态，并且该值仅取决于我们沿路径应用每个 di 的次数。 这表明我们不应该直接推理子集，而应该将问题视为可能的受众值的状态转换系统。 

一种更结构化的查看方式是定义剧集的动态过程，其中唯一有意义的状态是当前剧集索引和当前观众规模。 从状态 (i, c) 开始，我们有两种转换：跳过或采取。 采取产生奖励c·pi并移动到(i+1,floor(c/di))，而跳过移动到(i+1,c)。 然而，这个状态图仍然太大，因为 c 可以取很多值。 

关键的简化是 c 只从 m 除以不同的 di 中获取值。 由于 m ≤ 10^5，每个划分严格减少 c，并且每个 di ≥ 1。这意味着不同的可达观众值的数量很小，并且实际上受到我们在达到 1 之前可以划分的次数的限制。这使得仅使用可达状态（通常通过仅存储有用的转换来压缩）对剧集索引和当前观众值进行动态编程成为可能。 

因此，我们可以执行 DP，其中 dp[i][c] 是从第 i 集开始有 c 个观众的最大收入。 转换很简单，我们以相反的顺序进行计算。 由于当我们采取行动时 c 会减少，因此每个状态只会转换为更小的或相等的值，这使得记忆不会爆炸。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集 | O(n·2^n) | O(n·2^n) | O(n) | 太慢了|
 | DP 在 (i, c) 状态 | 最坏情况为 O(nm log m)，但在实践中修剪得更小 | O(纳米) | 已接受 |

 ## 算法演练

 我们定义了从后到前处理的情节的 DP。 在每一集 i 和观众值 c 处，我们决定是否投放广告。 

1. 我们初始化状态 (i, c) 的备忘录结构。 目标是计算从第 i 集开始，有 c 个观众的最佳可实现利润。 这代表了从那时起剩下的全部决策问题。 
2.我们处理从n到1的事件。向后处理是必要的，因为每个决策都取决于未来的结果，而向后DP确保这些结果是已知的。 
3. 在当前观众为 c 的第 i 集，我们计算两个选项。 如果我们跳过广告，状态会转换到 (i+1, c)，即时增益为零。 如果我们接受广告，我们立即获得 c·pi 并移动到 (i+1, Floor(c/di))。 
4. 我们将这两个选择中最好的存储为 dp[i][c]。 这确保了每个状态都记录从该点开始的最佳决策。 
5.答案是dp[1][m]，代表从第1集开始，全场观众。 

这样做的原因是该过程满足对 (i, c) 的最优子结构。 一旦我们确定了情节 i 和观众 c，所有未来的结果仅取决于这一对，并且除了通过 c 之外，任何早期决策都不会影响未来的转换。 因此，重新计算每个状态的最优选择就足够了，并且不存在跨状态耦合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
p = list(map(int, input().split()))
d = list(map(int, input().split()))

from functools import lru_cache

@lru_cache(maxsize=None)
def dp(i, c):
    if i == n:
        return 0

    # skip
    best = dp(i + 1, c)

    # take ad
    nc = c // d[i]
    best = max(best, c * p[i] + dp(i + 1, nc))

    return best

print(dp(0, m))
```代码直接实现状态定义。 函数 dp(i, c) 表示从第 i 集开始，有 c 个观众的最佳可能收入。 递归探索每一集中的两种选择。 记忆化确保每个状态被计算一次。 

除法步骤 c // d[i] 是唯一改变状态的转换。 使用整数楼层除法至关重要，因为问题明确需要它。 递归深度以 n 为界，但记忆化可以防止指数分支。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n·m) 最坏情况的记忆化，通常要少得多 | 每个状态 (i, c) 计算一次，并且 c 通过除法缩小 |

 给定 m ≤ 10^5，朴素 DP 状态空间很大，但可达状态通过重复的整数除法被大量修剪，这很快使 c 向 1 崩溃。

def run(inp: str) -> str:

    import math

 ## 边缘情况

 一个边缘情况是当所有 di 等于 1 时。在这种情况下，观众永远不会减少，因此最佳策略就是简单地获取每一集，因为每个广告独立贡献完整的 m·pi。 DP 自然会处理这个问题，因为状态 c 永远不会改变，因此每个情节决策都是独立的。 

另一种边缘情况是某些 di 非常大，可能等于 m。 这会立即将受众数量缩减为 1，因此以后的任何收益都是微乎其微的。 该算法可以正确处理此问题，因为在应用这样的事件后，所有未来状态都在 c = 1 上运行，从而防止高估。 

最后的边缘情况是当 pi 在序列后期变得非常大时。 天真的贪婪方法仍然会采取早期广告，但 DP 正确地探索跳过早期减少，为高价值剧集保留较大的 c，确保实现全局最优。
