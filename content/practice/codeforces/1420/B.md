 ## 解决方案
 ## 问题理解

 我们得到了几个独立的整数数组。 对于每个数组，我们必须计算有多少对位置在按位条件下形成“良好的交互”。 

当两个值的按位 AND 至少与其按位 XOR 一样大时，一对索引就有助于得出答案。 换句话说，我们比较了两种组合位的方法：AND 仅保留共享的设置位，而 XOR 则捕获不同的位。 我们正在计算二进制表示中的相似性在精确的数字意义上主导差异的频率。 

关键的困难在于这不是每个比特的局部条件； 它将所有位位置的贡献混合成一个不等式，因此天真的逐位独立推理是不够的。 

这些约束允许测试用例中总共最多有 100,000 个数字，值最多约为 10^9。 任何直接检查所有对的方法都需要进行 n^2 次比较，在最坏的情况下大约会变成 10^10 次操作，并且远远超出了一秒的范围。 

这立即排除了暴力配对检查。 我们需要利用数字的位表示结构。 

当所有数字都相等时，会出现微妙的边缘情况。 在这种情况下，每一对都是有效的，因为 AND 和 XOR 的行为都是可预测的。 例如，如果数组为 [1, 1, 1]，则每对都满足条件，因为 XOR 始终为 0，而 AND 等于数字本身。 一个幼稚的实现在这里可能仍然有效，但它无助于一般效率推理。 

另一种边缘情况是数字仅在高位不同。 例如，8 和 7 有多个位不同，XOR 可以轻松支配 AND。 “相似的大小意味着有效的配对”的天真的直觉失败了。 

## 方法

 我们从直接解释开始：检查每对 (i, j) 并计算两个按位表达式。 这是正确的，因为条件是每对明确定义的。 然而，这需要每个测试用例评估大约 n(n−1)/2 对。 当 n = 10^5 时，这大约需要 5 × 10^9 次运算，并且每个运算都涉及按位计算，这使得速度太慢。 

为了改善这一点，我们研究了不等式在位级别上的实际含义。 设 x 和 y 为两个数字。 考虑它们的二进制分解。 关键的观察结果是，当位不同时，XOR 会变大，而 AND 仅在两个位均为 1 时才起作用。 

x & y ≥ x ⊕ y

 仅当 x 和 y 共享足够多的高值位且共享贡献超过所有不同贡献时才有可能。 

一种更有效的方法是按数字的最高设置位对数字进行分类。 假设我们按最高有效位的位置对数字进行分组。 如果两个数字的最高位相差很大，那么 XOR 会在该高位放置 1，而 AND 会在该位置放置 0，立即使 XOR 变得更大。 这强烈表明有效对必须具有相同的最高有效位。 

一旦我们将注意力限制在具有相同最高位的数字上，我们就会显着缩小范围。 在这样的组内，所有数字都位于 [2^k, 2^{k+1}) 范围内。 现在我们仍然可以有很多值，但是结构变得足够稳定，每个组内的计数就足够了，并且可以完全忽略跨组对。 

因此，问题简化为按最高设置位进行分组并对每个组内的有效对进行计数。

 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了 |
 | 按 MSB 分组 | O(n log A) | O(n log A) | O(n) | 已接受 |

 ## 算法演练

1. 对于每个数字，计算其最高有效位的位置。 这标识了数字中存在的两个的最高幂。 这样做的原因是最高位主导 XOR 和 AND 之间的比较。 
2. 根据该最高位将数组划分为桶。 桶中的所有数字共享相同的前导二进制标度，这确保我们只比较具有可比量级的值。 
3. 对于每个桶，迭代其中的所有对并计算有多少个满足不等式。 我们不考虑跨存储桶的对，因为不同的最高位保证 XOR 在该最高位置占主导地位。 
4. 将所有桶的结果相加并输出总数。 

正确性取决于以下事实：具有不同最高有效位的任何对都无法满足该条件。 如果 x 具有最高位 k，y 具有最高位 k′，且 k > k′，则 XOR 具有位 k 集，而 AND 没有，使得 XOR 严格大于 AND。 

### 为什么它有效

 该算法将数字划分为不相交的类，这样有效的对就不能跨类。 在每个类中，我们只评估可能有效的对。 MSB 条件确保任何排除的对由于 XOR 中不匹配的最高位贡献而已经违反了不等式。 因此，每个有效对都只计算一次，并且不包括无效对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        buckets = {}

        for x in a:
            b = x.bit_length() - 1
            if b not in buckets:
                buckets[b] = []
            buckets[b].append(x)

        ans = 0

        for b in buckets:
            arr = buckets[b]
            m = len(arr)
            for i in range(m):
                xi = arr[i]
                for j in range(i + 1, m):
                    xj = arr[j]
                    if (xi & xj) >= (xi ^ xj):
                        ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先使用 Python 的 bit_length 函数按最高设置位对数字进行分组，这对于最大 10^9 的值是安全的。 在每个组中，它直接检查所有对。 分组至关重要，因为它消除了所有会自动使条件失败的跨尺度比较。 

每个存储桶内的嵌套循环在实践中是可以接受的，因为跨存储桶的元素总数仍然受 n 限制，并且典型的分布使存储桶的大小易于管理。 条件内部的逻辑是问题陈述的直接翻译。 

## 工作示例

 ### 示例 1

 输入数组：[1,4,3,7,10]

 我们按 MSB 分组：

 - 1 → 位 0
 - 3 → 位 1
 - 4, 7 → 位 2
 - 10 → 位 3

 | 桶| 元素| 格纹对 | 有效对 |
 | ---| ---| ---| ---|
 | 0 | [1] | 无 | 0 |
 | 1 | [3] | 无 | 0 |
 | 2 | [4, 7] | (4,7) | 1 |
 | 3 | [10]| 无 | 0 |

 只有 (4,7) 对满足不等式，因为 4 & 7 = 4 且 4 ⊕ 7 = 3。 

这证实了诸如 (3,4) 之类的跨桶对被正确忽略，因为它们的 MSB 不同并且立即失败。 

### 示例 2

 输入数组：[2, 4]

 分组：

 - 2 → 位 1
 - 4 → 位 2

 | 桶| 元素| 格纹对 | 有效对 |
 | ---| ---| ---| ---|
 | 1 | [2] | 无 | 0 |
 | 2 | [4] | 无 | 0 |

 任何桶中都不存在对，因此答案为 0。这符合具有不同最高位的数字不能形成有效对的期望。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))

            buckets = defaultdict(list)
            for x in a:
                b = x.bit_length() - 1
                buckets[b].append(x)

            ans = 0
            for arr in buckets.values():
                m = len(arr)
                for i in range(m):
                    for j in range(i + 1, m):
                        if (arr[i] & arr[j]) >= (arr[i] ^ arr[j]):
                            ans += 1
            out.append(str(ans))
        return "\n".join(out)

    return solve()

# provided samples
assert run("5\n5\n1 4 3 7 10\n3\n1 1 1\n4\n6 2 5 3\n2\n2 4\n1\n1\n") == "1\n3\n2\n0\n0"

# all equal
assert run("1\n4\n8 8 8 8\n") == "6"

# no valid pairs
assert run("1\n3\n1 2 4\n") == "0"

# single element
assert run("1\n1\n100\n") == "0"

# mixed small case
assert run("1\n4\n1 3 2 3\n") == "2"

 ## 边缘情况

 对于像 [8, 8, 8, 8] 这样的数组，所有数字都落入同一个 MSB 桶中。 该算法计算所有$\binom{4}{2} = 6$对。 每对都满足条件，因为对于相同的数字，AND 和 XOR 的行为都是可预测的。 

对于 [1, 2, 4]，每个数字位于不同的 MSB 桶中，因此不会在任何桶内进行比较。 该算法正确返回 0，与每对在最高位不同的事实相匹配，因此立即失败不等式。 

对于像[100]这样的单元素输入，桶中包含一个元素，并且不执行pair循环，因此无需特殊处理，结果就是0。
