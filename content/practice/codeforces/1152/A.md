 ## 解决方案
 ## 问题理解

 我们得到了一系列宝箱和一系列钥匙。 每个箱子上都写有一个数字，每个钥匙上也都写有一个数字。 只有当钥匙的数字之和为奇数时，才能打开箱子。 钥匙一旦使用就会消失，每个宝箱最多只能打开一次。 

任务是将钥匙与箱子配对，以满足奇偶条件并且成功配对的数量尽可能多。 

一个关键的观察是，只有平等才重要。 实际值无关紧要，除非它们是偶数还是奇数。 因此，每个箱子和钥匙都可以分为两组：偶数或奇数。 

约束条件$n, m \le 10^5$意味着任何尝试每一个宝箱钥匙组合的二次配对策略都会失败。 解决方案必须在线性时间内处理频率或计数，因为$O(nm)$的顺序是$10^{10}$运营。 

当其中一个奇偶校验组为空时，就会出现一种微妙的边缘情况。 例如，如果所有箱子都是偶数并且所有钥匙都是偶数，则根本不可能配对。 类似地，如果所有箱子都是奇数并且所有钥匙都是奇数，则同样不可能进行配对。 忽略奇偶校验分离并尝试任意匹配的幼稚实现将错误地假设存在某些匹配，除非明确检查。 

## 方法

 暴力解决方案将尝试每个胸部钥匙对并检查它们的总和是否为奇数。 如果有效并且两者都未使用，我们会贪婪地匹配它们。 这是正确的，因为每个有效配对都是独立的，但它太慢了。 高达$10^5$每个列表中的元素，这导致最多$10^{10}$检查，这是不可行的。 

关键的简化来自于认识到条件“和是奇数”相当于“一个是偶数，另一个是奇数”。 这将问题转化为两组之间的二分匹配：偶数和奇数。 然而，由于每个组内部没有额外的结构，因此我们不需要实际的图匹配算法。 任何偶数箱子都可以与任何奇数钥匙配对，反之亦然，因此只计算物质。 

因此，问题简化为计算两个数组中存在多少个偶数和奇数，然后贪婪地配对：每个偶数箱子可以与奇数钥匙匹配，每个奇数箱子可以与偶数钥匙匹配。 答案是这两个独立匹配的总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了 |
 | 计数奇偶校验| O(n + m) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 数一下有多少个箱子是偶数的，有多少个是奇数的。 

这将问题分为两个独立的类别。 
2. 数一下有多少个键是偶数，有多少个是奇数。 

这些计数确定所有可能的有效配对。 
3. 计算偶数箱子和奇数钥匙之间可以形成多少对。 

这受到两个计数中较小者的限制，因为每个对象都使用一次。 
4. 计算奇数箱子和偶数钥匙之间可以形成多少对。 

同样，这是可用计数的最小值。 
5. 将两个结果相加并输出。 

我们在每种情况下都取最小值的原因是，每次配对都会消耗一个箱子和一把钥匙，因此我们总是受到较小群体的瓶颈。 

### 为什么它有效

 奇偶校验条件完全决定了有效性：当且仅当元素具有相反的奇偶校验时，一对才有效。 一旦我们将项目分为偶数和奇数，就不再有链接特定元素的进一步约束。 任何将相反奇偶校验元素配对的匹配策略都是等效的，因此最大化匹配减少为最大化独立二分对计数，这是通过在两组之间贪婪地匹配尽可能多的对数来实现的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    even_a = sum(x % 2 == 0 for x in a)
    odd_a = n - even_a
    
    even_b = sum(x % 2 == 0 for x in b)
    odd_b = m - even_b
    
    # even chest with odd key
    match1 = min(even_a, odd_b)
    
    # odd chest with even key
    match2 = min(odd_a, even_b)
    
    print(match1 + match2)

if __name__ == "__main__":
    solve()
```该代码首先在一次传递中将两个数组拆分为奇偶校验计数。 然后它分别计算两个可能的配对方向。 最终答案是两者的总和，因为这些配对在使用的元素方面是不相交的。 

主要的微妙之处是确保我们不会错误地混合计数：偶数箱子只能与奇数钥匙匹配，反之亦然。 每个最小计算都强制执行一对一的使用约束。

 ## 边缘情况

 一种重要的边缘情况是一侧只有一种奇偶校验类型。 例如：

 输入：```
4 3
2 4 6 8
1 3 5
```在这里，所有箱子都是偶数，所有钥匙都是奇数。 该算法计算`even_chests = 4`,`odd_keys = 3`， 所以`min(4,3)=3`匹配，相反方向贡献为零。 输出为 3，这是正确的，因为每把钥匙都可以打开一个箱子，但有一个箱子尚未使用。 

另一种情况是双方混合但严重不平衡时：```
5 5
1 1 1 2 2
2 2 2 1 1
```奇偶配对给出`even_chests=2, odd_keys=3 → 2`和`odd_chests=3, even_keys=2 → 2`，总计 4。该算法正确地避免了过度计数，因为每个最小值都会强制消耗有限的资源。
