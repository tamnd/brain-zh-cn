 ## 解决方案
 ## 问题理解

 我们被要求计算一个角色访问的不同行星的有序序列，该角色从任何行星开始，然后精确地进行$k-1$移动。 每个动作都从当前星球开始$x$到一个新的星球$y$，有两个限制：$y$以前一定没有访问过，并且它必须位于范围内$[1, x + m]$。 访问后进程停止$k$不同的行星，如果两个序列在​​访问顺序中的任何位置不同，则它们被认为是不同的。 

关键是约束不是对称的。 从$x$，我们只能移动到右边不太远的行星，但是左边没有任何限制，除了该行星必须是未访问过的之外。 这会创建一个动态范围约束，该约束取决于迄今为止达到的当前最大位置。 

这些限制非常重要。 行星数量$n$取决于$10^5$，因此我们无法显式模拟所有序列。 然而，$k \le 12$，这是非常小的。 这立即表明指数算法$k$是可以接受的，只要它们不严重依赖$n$。 价值$m \le 4$进一步表明，转变是非常本地化和结构化的，这通常可以实现小社区周围的状态压缩。 

一个天真的想法是将每个状态视为$(visited\_set, current)$。 这会立即失败，因为访问集的大小最多为 12 个元素，选自$10^5$，这是一个天文数字。 

一个更微妙的问题是，即使我们忽略访问过的集合并尝试贪婪地计算每个位置的选择，我们也会忽略这样一个事实：可用性取决于当前位置以及附近哪些行星仍未使用。 

天真的贪婪思维的一个具体失败案例是$n=5, k=3, m=1$。 从位置 3，您可以转到位置 4，但如果先前已在不同分支中访问过 4，则该路径将变为无效，即使简单计数仍会包含它。 

因此，真正的困难是有效管理“已使用/未访问”状态，同时利用以下事实：$k$很小并且$m$非常小。 

## 方法

 暴力解决方案将尝试所有序列：从每个行星开始，递归地尝试所有有效的下一步动作，并维护一个已访问的数组。 每个步骤分支最多$m+1$候选人在最坏的情况下，因为从$x$我们最多可以去$x+m$, but only a constant number of those are relevant locally. 然而，递归深度是$k$，所以总复杂度大致为$O(n \cdot (m+1)^k)$，即使对于小常量来说，这也已经是边界了，真正的杀手是每次转换都需要检查候选节点是否被访问过，这使得有效状态空间取决于访问节点的实际身份。 

关键的观察是，唯一重要的“记忆”是在大小约为的滑动窗口内访问过的行星的相对结构$m+k$。 自从$m \le 4$和$k \le 12$，任何有效序列仅取决于当前最大位置周围的一个非常小的邻域。 一旦我们离得足够远，左边的行星就变得无关紧要，因为我们永远不能任意向后跳到未探索的结构中，从而影响超出有限地平线的未来可用性。 

这建议将状态压缩为位掩码，表示最后几个位置（相对于当前最大或当前参考点）已被使用。 自从$m$很小，转换只影响一个小的移动窗口，我们可以在这个窗口内对访问的模式进行编码。 

然后，我们对由当前位置和大小的位掩码定义的状态执行动态编程$O(m + k)$，但至关重要的是我们只需要跟踪相对偏移量$m$，因为转换仅检查该范围。 这将问题简化为位掩码 DP，大约为$2^{m+k}$每层的状态，以及$k \le 12$保持这一点易于管理。 

在每一步中，我们都会从一个状态转变$(current, mask)$到所有有效的下一个位置$y \in [1, current+m]$掩码表示中尚未访问的内容，相应地更新掩码。 

相对于暴力破解的改进在于，我们不跟踪绝对访问的节点，而是仅跟踪压缩的本地配置，并且我们不重新计算全局可达性，而是重用位掩码上的预先计算的转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n \cdot (m+1)^k)$|$O(k)$| 太慢了 |
 | 最佳 |$O(n \cdot 2^{k} \cdot k)$|$O(n \cdot 2^{k})$| 已接受 |

 ## 算法演练

 我们处理所有可能的起始行星，并且对于每个起始位置，我们在访问的节点数量上运行分层 DP。 

1. 初始化一个DP表，其中$dp[t][state]$表示构造有效长度序列的方法数$t$，以配置编码结束`state`。 该状态对相对于小窗口的当前位置以及已使用的附近位置进行编码。 
2. 对于每个起始行星$s$， 放$dp[1][initial\_state(s)] = 1$。 初始状态只有一个访问过的星球。 
3. 迭代步骤数$1$到$k-1$。 在每一步中，我们都会从层扩展所有 DP 状态$t$进入层$t+1$。 
4. 对于每个状态，解码当前位置$x$。 枚举所有候选的下一个位置$y$这样$1 \le y \le x+m$。 这个循环很小，因为$m \le 4$。 
5. 对于每位候选人$y$，检查是否已经在编码状态下被访问过。 如果没有被访问过，则通过标记构造一个新状态$y$访问过并将当前位置更新为$y$。 
6. 在下一个 DP 层中将旧状态中的路数添加到新状态中。 
7、后处理$k$层，对所有端点和起始位置的所有 DP 状态求和。 

这样做的原因是，每个有效序列都对应于通过这些 DP 状态的一条路径，因为状态编码在唯一可以影响未来移动的区域内保留了排序和访问信息。 由于转换仅取决于局部约束，因此导致相同局部掩模的两个不同的全局历史在未来的行为是相同的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

def solve():
    n, k, m = map(int, input().split())

    # We compress the DP using the fact k <= 12 and m <= 4.
    # We represent states as (current_position, visited_mask over last window).
    
    # Window size: we keep relative indices in [0 .. m+k]
    W = k + m + 1
    FULL = 1 << W

    # dp[position][mask] only for reachable positions
    dp = [dict() for _ in range(k + 1)]

    # initialize
    for s in range(1, n + 1):
        mask = 1 << (s % W)
        dp[1][(s, mask)] = (dp[1].get((s, mask), 0) + 1) % MOD

    for t in range(1, k):
        ndp = [dict() for _ in range(k + 1)]
        for (x, mask), val in dp[t].items():
            for y in range(1, min(n, x + m) + 1):
                bit = 1 << (y % W)
                if mask & bit:
                    continue
                nm = mask | bit
                key = (y, nm)
                ndp[t + 1][key] = (ndp[t + 1].get(key, 0) + val) % MOD
        dp = ndp

    ans = 0
    for state, val in dp[k].items():
        ans = (ans + val) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
