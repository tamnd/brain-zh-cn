 ## 解决方案
 ## 问题理解

 任务是重建一个正整数数组，`a`，给定两个数组`b'`和`c'`。 这些数组是从生成的`a`通过两个阶段：首先，将所有连续的对放入`a`形成`b`和`c`，其中每个`b_i`是最小值并且每个`c_i`是该对中的最大值`(a_i, a_{i+1})`; 其次，通过排列`b`和`c`有一些未知的排列`p`生产`b'`和`c'`。 挑战是逆转这个过程并产生任何有效的原始数组`a`，或者确定不存在这样的数组。 

输入由一个整数组成`n`和两个数组`b'`和`c'`，每个长度`n-1`。 输出要么是有效的`a`长度`n`或者`-1`如果重建是不可能的。 限制条件`2 ≤ n ≤ 10^5`和`1 ≤ b'_i, c'_i ≤ 10^9`建议复杂度以上的算法`O(n log n)`可能太慢，而线性或近线性解决方案是可行的。 

非明显的边缘情况包括多对具有相同最小值或最大值的序列，例如`b' = [1,1,1]`和`c' = [2,2,2]`。 不考虑冲突而按顺序分配值的天真的贪婪方法可能会产生负面结果或不一致的序列。 当连续元素必须满足相互冲突的最小-最大约束时，就会出现另一个棘手的情况`b'`和`c'`， 例如`b' = [2,3]`和`c' = [3,2]`。 该算法必须验证每一对都是兼容的，并且最终的数组`a`不违反任何最小-最大关系。 

## 方法

 蛮力方法会尝试每一种排列`b'`和`c'`,尝试重建`a`，并验证与最小-最大定义的一致性。 为了`n-1`元素，有`(n-1)!`排列。 每个排列都需要重建`a`检查有效性，每个排列的复杂度为 O(n)。 这种方法理论上是正确的，但实际并不可行`n`最多`10^5`因为`(n-1)!`是一个天文数字，远远超出了任何计算极限。 

关键的观察是每个元素`a`正好出现在两个连续的最小-最大对中：对于元素`a_i`（除了第一个和最后一个），`a_i`是一部分`b_{i-1}`,`c_{i-1}`,`b_i`， 和`c_i`。 因此，我们可以将其建模为图形问题：每对`(b'_i, c'_i)`定义两个连续元素之间的边`a`，其中一个元素是最小值，另一个是最大值。 通过将每一对视为无向边并尝试一致地分配端点，问题就简化为将这些对排列为一条链，其中值在共享节点处匹配。 我们只需要考虑第一对的两种可能性并按顺序传播选择。 如果在任何步骤不能满足最小-最大约束，则重建是不可能的。 

这种见解将复杂性从阶乘降低到线性，因为我们仅根据第一对的两个可能分配来探索最多两个序列。 传播确保每个后续元素要么匹配，要么导致矛盾。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O((n-1)!) | O((n-1)!) | O(n) | 太慢了 |
 | 带有传播的顺序分配 | O(n) | O(n) | 已接受 |
