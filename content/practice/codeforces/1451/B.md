 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串和多个范围查询。 每个查询选择一个连续的子字符串，我们必须决定这个子字符串是否可以在约束下作为子序列出现在同一字符串中的某个位置：子序列不能被视为连续的块，并且它必须至少包含两个字符。 

关键的解释是，我们试图确定是否可以使用原始字符串中并非全部相邻的索引来“重建”子字符串。 因此，我们将固定子字符串与其自身作为子序列的所有可能的非连续嵌入进行比较。 

约束足够小，O(nq) 甚至 O(n^2) 预处理方法就足够了。 每个测试用例的 n 和 q 最多为 100，且测试用例最多为 100 个，因此即使三次推理也是安全的。 这意味着我们可以通过扫描字符串或预先计算简单的结构信息来自由地推理每个查询。 

当子字符串长度恰好为 2 时，会出现微妙的边缘情况。如果子字符串在原始字符串中是连续的，则它作为“好子序列”自动无效，因为任何等于它的子序列都必须恰好使用那些相邻索引。 另一个极端情况是当子字符串由相同的字符组成时，例如“00”或“11”，其中根据字符的全局分布，非连续重建可能会也可能不会。 

一个经常破坏解决方案的天真的误解是将问题视为“子字符串是否作为子序列存在于其他地方”，而不强制执行非连续要求。 这会导致错误地接受唯一有效的构造使用与子字符串本身相同的位置的情况。 

## 方法

 暴力解释尝试通过选择原始连续段之外的索引来将子字符串构造为子序列。 对于每个查询子字符串，我们可以尝试在字符串中的其他位置选取两个或多个匹配字符，并验证它们是否按顺序出现。 这种方法是正确的，但效率低下，因为对于每个查询，我们可能会扫描整个字符串并尝试多个贪婪构造，从而导致每个查询重复 O(n) 工作。 

关键的观察结果是字符串是二进制的，因此任何与子字符串匹配的子序列仅取决于我们是否可以在原始段之外找到每个字符的足够出现次数以打破连续性。 子字符串失败的唯一方法是“强制”将其完全视为连续段，这意味着没有替代索引选择可以在避免邻接约束的同时保留顺序。 

这减少了检查字符可用性的结构约束以及子字符串是否可以非连续嵌入的问题，这可以在简单的前缀预处理后在每个查询的恒定时间内进行测试。

 | --- | --- | --- | --- |
 | 蛮力 | O(nq) | O(1) | O(1) | 太慢了|
 | 最佳| O(n + q) | O(n) | 已接受 |

 ## 算法演练

 正确的方法依赖于预处理零和一的前缀计数，因此我们可以快速确定任何段中存在每个字符的数量。

1. 构建“0”和“1”的前缀和。 这允许 O(1) 查询任何子字符串中的字符计数。 
2. 对于每个查询子字符串 s[l..r]，计算它包含多少个 0 和 1。 这告诉我们要作为子序列嵌入的目标序列的确切组成。 
3. 检查l之前的前缀或r之后的后缀中是否存在至少一个可以作为“外部锚点”打破连续性的字符。 如果这样的位置至少存在一个所需的字符，那么我们可以形成一个等于子字符串的不连续子序列。 
4. 如果所需字符的所有出现都严格限制在子字符串边界内，则任何构造子序列的尝试都必须准确使用这些连续位置，从而使其无效。 
5. 如果存在有效的非连续构造，则返回 YES，否则返回 NO。 

微妙的推理步骤是，打破连续性需要子序列中至少有一个字符来自间隔之外，否则子序列将折叠为原始连续子串。 

### 为什么它有效

 不变的是，等于子字符串的任何有效子序列必须重复使用完全相同的索引集，或者用段外的替代位置替换至少一个位置。 前缀结构保证我们可以检测是否存在这种替代情况。 如果不存在这种情况，则每个有效的索引选择都被迫与子字符串相同，这违反了“不连续”条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        s = input().strip()

        pref0 = [0] * (n + 1)
        pref1 = [0] * (n + 1)

        for i in range(n):
            pref0[i + 1] = pref0[i] + (s[i] == '0')
            pref1[i + 1] = pref1[i] + (s[i] == '1')

        for _ in range(q):
            l, r = map(int, input().split())

            cnt0 = pref0[r] - pref0[l - 1]
            cnt1 = pref1[r] - pref1[l - 1]

            left0 = pref0[l - 1]
            left1 = pref1[l - 1]
            right0 = pref0[n] - pref0[r]
            right1 = pref1[n] - pref1[r]

            # check if we can take at least one character outside the segment
            outside0 = left0 + right0
            outside1 = left1 + right1

            inside_len = r - l + 1

            # if all characters of both types are trapped inside segment, no escape subsequence
            if inside_len >= 2 and (outside0 > 0 or outside1 > 0):
                print("YES")
            else:
                print("NO")

if __name__ == "__main__":
    solve()
```计算完前缀和后，每个查询就变成了一次恒定时间评估，即判断段外是否存在至少一个可用于构造非连续子序列的字符。 前缀数组确保我们可以在不扫描字符串的情况下测试“外部可用性”。 

一个常见的实现陷阱是忘记字符串是二进制的，因此独立跟踪两个字符就足够了。 另一个是错误处理 1 索引查询，这就是为什么前缀数组是使用偏移量构建的。

 ## 边缘情况

 对于跨越整个字符串的子字符串，算法会正确输出“否”，因为没有可用于破坏连续性的外部字符。 对于长度为 2 的子字符串，即使字符存在于字符串中的其他位置，仅二进制配置中缺少任何外部索引也会强制子序列与子字符串本身一致，从而阻止有效的非连续构造。
