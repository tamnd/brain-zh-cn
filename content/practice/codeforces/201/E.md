 ## 解决方案
 ## 问题理解

 该问题涉及一组人，每个人在接下来的 _n_ 天内的唯一一天都有约会。 您不知道哪一天安排了谁，但您可以在最多列出 _m_ 个姓名的表单中查询组织。 答复给出了所列姓名的预约日期，但内容是混乱的。 您的目标是使用最少的表格确定每个人的确切日期。 

对于每个测试用例，输入为 _n_（人数）和 _m_（您可以在单个请求中列出的姓名数量）。 输出是确定每个约会日期所需的最少请求数。 

问题的边界（_n_ 和 _m_ 最多 10^9 以及最多 1000 个测试用例）排除了任何模拟约会或显式生成所有子集的解决方案。 我们必须进行数学推理并用简单的算术计算出答案。 

当 _m_ ≥ _n_ 时，会出现不明显的边缘情况。 在这种情况下，您可以在单个请求中查询所有人员，但由于响应是混乱的，因此可以通过消除推断出一个人的日期，因此您需要的请求可能比看起来要少。 另一个边缘情况是 _n = 1_，其中不需要查询，因为唯一的约会是众所周知的。 

## 方法

 暴力方法会考虑枚举请求中的所有人员组合，并检查混乱的响应是否足以确定每个人的预约。 这在原则上是正确的，但是是组合性的：在 _n_ 中存在指数级数量的子集，其大小高达 _m_，并且对于 _n_ 高达 10^9 的情况检查它们是不可行的。 

关键的见解是从覆盖范围的角度进行思考。 每个请求最多可以提供 _m_ 个人的信息。 一旦您知道 _n-1_ 个人的预约日期，最后一个人的日期就通过排除法确定。 这意味着您永远不需要单独查询所有_n_个人。 因此，请求的最小数量是最小整数_k_，使得跨越_k_个请求的“槽”总数至少为_n-1_。 每个请求最多贡献 _m_ 个槽，因此公式变为：```
requests = ceil((n - 1) / m)
```这个简单的公式可以有效地处理 _n_ 和 _m_ 的所有大值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 数学公式| 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取测试用例的数量_t_。 
2. 对于每个测试用例，读取值 _n_ 和 _m_。 
3. 如果_n = 1_，则立即输出0，因为不需要查询。 
4. 否则，使用整数算术计算最小请求数：`(n - 1 + m - 1) // m`。 这相当于上限除法，确保我们始终向上舍入。 
5. 打印结果。 

这样做的原因是，在查询了_n-1_个人之后，最后一个人的预约是唯一确定的。 每个请求最多贡献 _m_ 个已知预约，因此将所需的已知时隙总数 (_n-1_) 除以 _m_ 并向上舍入可保证完全覆盖。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    if n == 1:
        print(0)
    else:
        print((n - 1 + m - 1) // m)
```第一行读取测试用例的数量。 我们使用`sys.stdin.readline`用于快速输入，因为最多可以有 1000 个测试用例。 每个循环读取两个整数，检查 _n = 1_ 的简单情况，否则应用上限除法公式`(n - 1 + m - 1) // m`计算最小请求数。 

## 工作示例

 **示例 1：** n = 4，m = 1

 | 变量| 价值|
 | --- | --- |
 | n-1 | n-1 3 |
 | 米 | 1 |
 | 请求 | (3 + 0) // 1 = 3 |

 需要三个请求，每个请求查询一个人。 前三个查询显示三个日期，第四个日期通过排除法确定。 

**示例 2：** n = 4，m = 2

 | 变量| 价值|
 | --- | --- |
 | n-1 | n-1 3 |
 | 米 | 2 |
 | 请求 | (3 + 1) // 2 = 2 |

 两个请求就足够了。 第一个请求可以查询两个人，第二个请求可以查询两个人（可能与第一个请求重叠），从而提供足够的覆盖范围来推断所有四个日期。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(input())
    results = []
    for _ in range(t):
        n, m = map(int, input().split())
        if n == 1:
            results.append("0")
        else:
            results.append(str((n - 1 + m - 1) // m))
    return "\n".join(results)

# Provided samples

 ## 边缘情况

 当_n = 1_时，公式`(n-1 + m-1)//m`正确计算结果为 0。对于 _m ≥ n_，该公式简化为`(n-1 + m-1)//m = (n-1)//m + 1`如果需要，当 _n > 1_ 时正确输出 1，因为最后一个日期是通过消除推导出来的。 当_m = 1_时，每个请求只能覆盖一个人，因此算法正确输出_n-1_个请求。 这些检查涵盖了所有重要的场景。
