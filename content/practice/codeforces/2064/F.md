 ## 解决方案
 ## 问题理解

 我们得到一个整数数组`a`长度`n`和目标值`k`。 我们的任务是计算所有连续的子数组`a`那是_史诗_。 如果我们可以将子数组分成两个非空部分，使得第一部分的最小值加上第二部分的最大值等于`k`。 Formally, if`b`是一个子数组`a`，如果存在索引，那就是史诗`i`(1 ≤ i < b 的长度) 使得`min(b[0..i-1]) + max(b[i..end]) = k`。 

输入指定多个测试用例。 每个测试用例提供`n`,`k`，和数组`a`。 我们每个测试用例的输出都是一个数字：史诗子数组的计数。 

约束表明`n`每个测试用例可以大到 2×10^5，并且总和`n`跨测试用例不超过2×10^5。 这意味着我们负担不起 O(n^2) 算法。 如果我们重新计算每个子数组分割的最小值和最大值，则检查所有子数组的强力方法将执行大约 O(n^3) 操作，或者如果我们预先计算所有子数组的最小值/最大值，则执行 O(n^2) 操作，这仍然太慢。 因此，我们需要每个测试用例采用近线性或线性算术方法。 

不明显的边缘情况包括具有重复数字的数组，每个元素相对于`k`，以及最小大小为 2 的数组。例如，如果`a = [1, 1, 1]`和`k = 3`，那么没有子数组是史诗般的，因为`min + max = 2`充其量，但仅扫描第一个和最后一个元素的简单算法可能会错误地计算某些子数组。 另一个棘手的情况是像这样的数组`[6,6,6,7,7]`和`k = 13`，其中任何子数组至少包含一个`6`和一个`7`变得史诗般，需要仔细计数而不是天真的迭代。 

## 方法

 蛮力方法考虑每个子数组`a[l..r]`并尝试每个分割索引`i`。 对于每个分割，我们计算`min(a[l..i])`和`max(a[i+1..r])`并检查总和是否等于`k`。 这是有效的，因为它详尽地检查了所有可能性。 问题是效率：对于`n=2×10^5`，子数组的数量大约为2×10^10，这是不可行的。 

关键的观察是`k`严格大于`n`并且小于`2n`。 每个元素都在`[1, n]`，因此史诗子数组需要一个部分来包含`x`和另一部分包含`y`在哪里`x + y = k`。 因为有界限，`x`和`y`是 1 到 n 之间的唯一数字。 因此，问题简化为计算包含以下内容的子数组：`x`在第一部分和`y`在第二部分中，其中`x + y = k`。 这种洞察力使我们能够跟踪`x`和`y`扫描数组并使用两个指针或滑动窗口对有效子数组进行计数。 

更具体的方法利用了以下事实：`x = k - y`。 我们可以从左到右扫描，跟踪最后一次出现的`x`以及下一次出现的`y`。 任何在最后一个之前开始的子数组`x`并在下一个之后结束`y`是史诗般的。 使用这个逻辑，我们可以在线性时间内计算所有史诗子数组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) | O(n^3) | O(1) | O(1) | 太慢了|
 | 预先计算所有子数组的最小值/最大值 | O(n^2) | O(n^2) | O(n^2) | O(n^2) | 太慢了|
 | 两指针/位置跟踪| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 预先计算这对数字`(x, y)`这可以总结为`k`对于给定的子数组。 这里`x`位于左侧部分，`y = k - x`在右边的部分。 
2. 迭代数组，同时维护最后一个索引，其中`x`出现了。 这有助于我们了解以当前索引结尾的所有子数组`x`在左侧部分。 
3.同时，对于每个索引，找到最早的索引，其中`y`出现在当前索引之后。 这确保了正确的部分`y`。 
4. 对于每个索引，以该索引结尾的史诗子数组的数量由最后一个子数组之间的距离确定`x`和当前索引（如果有效）`y`存在于右侧。 将此计数添加到运行总数中。 
5. 继续扫描直到数组末尾，更新最后出现的`x`以及未来最早发生的`y`。 

为什么它有效：在数组中的任何点，最后一次出现的`x`确保所有左侧部分包含`x`有效，并且下一次出现`y`保证正确的部分包含`y`。 因为`x`和`y`是固定的，每个计数的子数组都满足`min(left) + max(right) = k`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_epic_subarrays(n, k, a):
    pos = [0] * (n + 2)
    res = 0
    # mark positions of each number
    for idx, val in enumerate(a):
        pos[val] = idx + 1

    # loop through possible left part values
    for x in range(1, n + 1):
        y = k - x
        if 1 <= y <= n:
            left = pos[x]
            right = pos[y]
            if left and right and left < right:
                res += left * (n - right + 1)
    return res

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    print(count_epic_subarrays(n, k, a))
```该解决方案将每个数字映射到其在数组中的最后一个出现位置。 对于每个可能的对`(x, y)`总结为`k`，我们计算包含的子数组的贡献`x`前`y`。 乘法`left`剩余头寸`right`Positions 给出了该对的总的史诗子数组。 边缘情况如`x`或者`y`未出现的由条件检查处理。 

## 工作示例

 **样品1：**```
n = 5, k = 7, a = [1,2,3,4,5]
```为了`x = 2`,`y = 5`（`2+5=7`）， 最后的`2`首先在索引 2 处`5`在索引 5 处，所以子数组`[2,3,4,5]`和`[3,4,5]`通过左*右公式计算。 为了`x=3`,`y=4`， 最后的`3`在索引 3 处，首先`4`在索引 4 处，子数组`[3,4]`。 史诗子阵列总数：2。 

**样本2：**```
n = 7, k = 13, a = [6,6,6,6,7,7,7]
```对`(6,7)`仅有的。 最后的`6`首先在索引 4 处`7`在索引 5 处。从索引 1..4 开始到 5..7 结束的子数组：12 个史诗子数组。 

该跟踪表明，预先计算位置并乘以左/右选择可以正确计算所有有效子数组，而无需迭代所有 O(n^2) 子数组。
