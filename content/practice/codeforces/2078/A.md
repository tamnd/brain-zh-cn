 ## 解决方案
 ## 问题理解

 我们得到一个整数数组和一个目标值。 目标是重复地将数组分割成大小相等的部分，用这些部分的平均值替换数组，并继续下去，直到数组只剩下一个元素。 我们必须确定是否存在以单个元素等于目标结束的一系列此类操作。 

输入包括多个测试用例。 每个测试用例提供数组长度`n`, 目标`x`，和数组`a`本身。 数组元素和`x`都是正整数，并且`n`最多 100。这意味着我们可以负担时间复杂度高达大约 100 的算法$O(n^2)$每个测试用例。 对所有可能的分割进行暴力破解会变得很麻烦，特别是因为对于每个分割，我们都需要计算平均值并递归。 

当数组已经是单个元素或所有元素都相同时，会出现不明显的边缘情况。 例如，如果`a = [3]`和`x = 3`，我们可以立即返回YES。 如果`a = [5,5,5]`和`x = 5`，答案也是肯定的，但这是一种幼稚的方法，它寻找总和恰好等于`x`可能会错误地拒绝它。 当目标`x`等于数组的平均值，但不等于任何单个元素。 例如，`a = [1, 2]`和`x = 1.5`无法实现，因为我们的分割必须产生整数长度的子序列，并且如果所有元素都是整数（它们在这里），则对它们求平均只会产生整数。 

## 方法

 暴力方法会在每一步尝试每一种可能的分割，递归计算平均值。 这在技术上是正确的，因为任何有效的操作序列都必须是一系列此类拆分。 然而，分割数组的方法数量随着组合而增长`n`，使得这种方法即使对于`n = 20`。 为了`n = 100`，这是不可行的。 

关键的见解是，在每次操作中，数组的新元素都是当前数组元素的凸组合。 这意味着最终值`x`必须位于原始数组的最小值和最大值之间。 如果`x`等于其中一个元素，答案是肯定的。 否则，如果`x`在数组的范围内但不完全等于任何元素，我们总是可以构造一个平均为的分割序列`x`首先取整个数组的平均值。 具体来说，我们总是可以将所有元素合并到一个长度的子序列中`n`（整个数组），产生平均值。 因此，条件简化为检查是否`x`要么等于任何元素，要么等于数组的平均值。 

这一观察让我们将问题简化为数组的线性扫描：检查是否`x`是在`a`或等于平均值`a`。 这是快速的并且在限制范围内很适合。

 ## 算法演练

 1. 对于每个测试用例，请阅读`n`,`x`，和数组`a`。 
2. 计算数组元素的总和。 
3. 检查是否`x`等于任意元素`a`。 如果是，则打印“YES”并继续下一个测试用例。 这涵盖了我们可以立即选择单元素子序列的简单序列。 
4. 否则，检查是否`x * n == sum(a)`。 这验证是否`x`正是数组的平均值。 如果是，则打印“YES”。 原因是，将整个数组分成一组并取平均值会产生`x`。 
5. 如果两个条件都不满足，则打印“NO”。 不允许的操作序列不能产生`x`在这种情况下。 

为什么它有效：允许的操作用相等大小的子序列的平均值替换数组。 任何生成的平均值都是现有元素的凸组合，因此最终元素必须位于原始数组的最小值和最大值之间。 如果目标与某个元素或总体平均值匹配，则存在明确的分割序列来达到它。 否则，任何序列都无法产生它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, x = map(int, input().split())
    a = list(map(int, input().split()))
    
    if x in a:
        print("YES")
    elif sum(a) == x * n:
        print("YES")
    else:
        print("NO")
```该解决方案首先读取测试用例的数量。 对于每个测试用例，它读取数组并计算总和。 检查`x in a`立即处理最简单的情况。 比较`sum(a)`到`x * n`处理平均值等于目标的情况。 乘法`x`经过`n`避免浮点精度问题。 如果两个条件都不成立，则打印“NO”。 这种方法简单、快速，并且避免了不必要的递归。

 ## 边缘情况

 如果数组有一个元素等于`x`，算法立即返回“YES”。 为了`a = [3]`和`x = 3`, 支票`x in a`通过。 例如，如果目标等于平均值​​但没有单个元素与之匹配`a = [1,9,14,12,10,8]`和`x = 9`, 支票`sum(a) == x * n`通过，产生“YES”。 所有元素都相等的数组会被正确处理，因为两项检查都会成功。 两个条件都不成立的数组，例如`a = [1,2]`和`x = 5`，正确产生“NO”。
