 ## 解决方案
 ## 问题理解

 每个学生都回答多项选择测试$m$问题，每个问题有五个可能的选项。 我们收到了每个学生的完整答卷，但正确答案未知。 我们控制的是每个问题正确答案的假设选择，以及每个问题$j$有固定分数$a_j$如果回答正确。 

如果我们确定某个问题的某个特定选项是正确的，则每个选择该选项的学生都会获得该问题的相应分数。 我们的任务是以最大化所有学生得分总和的方式为每个问题分配正确的选项（A 到 E）。 

该结构在各个问题之间是独立的。 我们对问题所做的选择$j$不会影响任何其他问题，因为分数线性增加并且学生的答案是固定的。 

限制条件$n, m \le 1000$意味着在简单的实现中最多进行一百万个字符检查。 任何扫描每个学生每个问题的答案的解决方案都足够快，因为$O(nm)$经营规模较小。 

一个天真的错误是假设我们需要模拟不同的全局答案键或尝试同时对齐多个问题。 例如，认为我们必须在独立最大化之外的问题上选择一致的模式会导致不必要的复杂性。 另一个常见的陷阱是忘记正确答案是根据问题独立选择的，而不是根据学生选择的。 

## 方法

 一个蛮力的想法是尝试所有可能的正确答案字符串长度$m$，其中每个位置有 5 个选择。 这给出了$5^m$可能性，即使对于小企业来说也是天文数字$m$。 对于每个候选答案键，计算总分需要检查所有$n$对面的学生$m$问题，导致$O(nm)$每个候选人。 这很快就变得不可行。 

关键的观察结果是问题不会相互作用。 对于固定问题$j$，如果我们决定该选项$A$是正确的，该问题贡献的分数很简单$a_j$乘以选择的学生人数$A$。 B、C、D、E也是如此。因此，对于每个问题，我们只需要选择学生中最常见的答案即可。 

这将问题简化为计算输入矩阵每列的频率计数，然后在每列的五个固定选项中选择最佳选项。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(5^m \cdot nm)$|$O(1)$| 太慢了 |
 | 最佳 |$O(nm)$|$O(1)$额外 | 已接受 |

 ## 算法演练

 1. 将结果累加器初始化为零。 这将存储所有问题的总最高分。 
2.对于每个问题索引$j$，为五个可能的选项构建一个频率计数器。 我们扫描所有学生并计算有多少人选择了该列的 A、B、C、D 和 E 中的每一个。 
3. 计算出问题的频率后$j$，通过取五个选项中的最大频率并将其乘以来计算可实现的最佳贡献$a_j$。 
4. 将此贡献添加到总累加器中。 
5. 对所有问题重复上述步骤。 

此步骤有效的原因是问题的正确性仅取决于有多少学生匹配所选答案。 由于我们可以自由地声明任何选项是正确的，因此我们总是选择支持度最高的选项。 

### 为什么它有效

 对于每个问题$j$，任何正确答案的分配都对应于选择五组学生中的一组。 分数与组大小呈线性关系，因此最大化贡献可以减少选择最大组的过程。 由于问题是独立的，因此对局部最优值求和可产生全局最优值而不会受到干扰。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    students = [input().strip() for _ in range(n)]
    scores = list(map(int, input().split()))

    total = 0

    for j in range(m):
        freq = [0] * 5
        for i in range(n):
            c = students[i][j]
            freq[ord(c) - 65] += 1

        best = max(freq)
        total += best * scores[j]

    print(total)

if __name__ == "__main__":
    solve()
```该解决方案读取所有学生字符串，然后逐列迭代。 对于每一列，它都会构建一个长度为 5 的小型固定大小频率数组。 转换`ord(c) - 65`将字符 A 到 E 映射到索引 0 到 4。这可以保持实现的紧凑性并避免条件链。 

乘以`scores[j]`仅在确定最常见的答案后才会发生，以确保我们不会多算。

 ## 边缘情况

 一种极端情况是所有学生对一个问题选择不同的答案。 例如：```
3 1
A
B
C
10
```对于单列，频率都是1。算法选择其中任何一个，给出贡献$1 \cdot 10 = 10$。 轨迹很简单：频率数组变成$[1,1,1,0,0]$，最大值为1，所以结果是正确的。 

另一个边缘情况是当$n = 1$。 该算法仍然有效，因为频率数组将有一个 1 和四个 0，并且贡献只是问题分数。 

最后一个边缘情况是$m = 1$。 该算法简化为计算单个字符串列中最常见的字符，它仍然匹配相同的逻辑而无需修改。
