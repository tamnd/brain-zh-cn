 ## 解决方案
 ## 问题理解

 我们得到一个数字列表，然后重复执行一个操作，选择两个不同的位置并将两个值都减一。 目标是确定我们最终是否可以使用某些此类操作序列将每个值精确地降至零。 

每个操作仅消耗两个不同元素的一个单元。 如果您从“工作单元”的角度思考，则每次操作总共会删除两个单元，但它们必须同时来自两个不同的堆。 问题是整个阵列中单元的初始分布是否可以像这样完全配对，直到没有任何剩余。 

的约束条件为`n`最多$10^5$值高达$10^9$立即排除任何模拟操作。 即使我们尝试贪婪地模拟递减，操作总数也可能约为$10^9$，这远远超出了可行的限度。 该解决方案必须依赖于可以在线性时间内检查的结构条件。 

如果我们尝试幼稚的推理，就会出现一些微妙的失败案例。 例如，人们可能认为只要总和是偶数，答案就是“是”。 这失败了：考虑`[1, 1, 1]`，其中总和为 3（已经是奇数，因此被拒绝），但也`[2, 2, 1, 1]`总和为 6，看起来很有希望。 然而，如果一个元素占主导地位太多，配对约束仍然可能使其变得不可能。 

另一个天真的想法是贪婪地配对最大的元素，直到耗尽为止。 在以下情况下这可能会失败`[3, 3, 1, 1]`，贪婪配对有效，但在`[4, 1, 1, 1]`，贪婪配对很快就会陷入困境，尽管结构本身已经保证了不可能。 

因此，真正的困难不是模拟，而是识别何时存在有效的配对结构。 

## 方法

 每个操作都会从两个不同的索引中删除一个单位，因此该过程可以解释为将不同索引中的各个单位贡献配对。 将每个数组元素想象为一堆单元标记。 我们需要将每个令牌与来自不同堆栈的令牌进行匹配。 

如果我们将数组扩展为单元标记的多集，任务就变成：我们能否将所有标记配对，使得没有一对来自同一索引？ 这立即表明了两个必要条件。 

首先，令牌总数必须是偶数，因为每个操作恰好删除两个单元。 如果总和为奇数，则至少有一个单元将保持未配对状态。 

其次，与其他元素相比，任何单个元素都不能太大。 如果一个值超过所有其他值的总和，则不可能继续将其单元与不同元素配对，因为最终我们会用完外部标记来匹配它。 正式来说，如果`max(a)`大于`sum(a) - max(a)`，那么最大的一堆就不能完全匹配。 

这两个条件也足够了。 如果它们成立，我们总是可以贪婪地构造配对而不会被卡住，因为大堆总是由足够的小堆支撑以吸收它们的减量。 

蛮力的想法将模拟操作，总是选择两个非零元素并递减它们，直到没有剩余移动或达到所有零。 这在概念上可行，但可能需要$O(\sum a_i)$操作，当值很大时这是不可行的。 

关键的见解是我们不需要模拟配对；我们需要模拟配对。 我们只需要验证由单位守恒和配对约束导出的可行性条件。

 | ---| ---| ---| ---|
 | 暴力模拟| O(a_i 总和) | O(1) | O(1) | 太慢了 |

 ## 算法演练

 1. 计算数组的总和。 这代表所有操作所需的单位移除总数。 由于每个操作恰好删除 2 个单位，因此对于任何存在的解，该总和必须为偶数。 
2. 如果总和是奇数，立即断定不可能。 任何操作序列都无法移除单个剩余单元。 
3. 确定数组中的最大元素。 该值表示最受约束的堆，因为其中的每个单元都必须与另一个索引中的单元配对。 
4. 计算除最大值之外的所有剩余元素的总和。 这代表了可以与最大堆配对的总可用“外部容量”。 
5. 如果最大元素大于该剩余总和，则返回“NO”。 这表明，即使我们以最佳方式使用所有其他元素，我们仍然没有足够的不同单元来匹配最大堆中的所有单元。 
6. 否则，返回“YES”，因为全局奇偶性和局部可行性约束都满足。 

### 为什么它有效

 该过程可以看作是在完全匹配中构建边，其中每个索引贡献与其值一样多的顶点。 这些约束确保存在完美匹配而无需自配对。 

奇偶校验条件强制原则上甚至可以实现完美匹配。 支配条件确保没有顶点集太大而无法进行外部匹配。 总之，这些保证了贪婪配对过程始终可以继续而不会陷入困境，因为在每个阶段都至少有一个替代索引与最大堆中的任何选定单元配对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    mx = max(a)
    
    if total % 2 != 0:
        print("NO")
        return
    
    if mx > total - mx:
        print("NO")
        return
    
    print("YES")

if __name__ == "__main__":
    solve()
```该代码首先计算单遍中的总和和最大值。 奇偶校验在其他任何操作之前执行，因为它是严格的必要条件。 第二个检查强制将最大元素与所有其他元素组合配对的可行性。 该顺序只影响早期退出效率，而不影响正确性。

 ## 边缘情况

 关键的边缘情况是一个元素完全等于所有其他元素的总和。 例如，`[4, 1, 1, 2]`。 总和为 8，为偶数，最大为 4，剩余和为 4。 条件`mx > total - mx`为假，因此算法接受这种情况。 这是正确的，因为最大的一堆可以与所有剩余的单元精确配对，而不会剩下任何东西。 

另一个微妙的情况是`[1, 1]`。 和为 2，偶数，最大为 1，剩余和也是 1。算法接受它，匹配单个可能的操作，直接将两个元素都减少到零。 

像这样的案例`[3, 3, 3]`被拒绝，因为总和是 9，奇偶校验立即失败。 即使值是平衡的，配对总是会删除两个单位，因此不可避免地会保留一个单位。
