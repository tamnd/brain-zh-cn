 ## 解决方案
 ## 问题理解

 我们得到一个数组，并要求回答有关子数组的非常具体的聚合的许多查询。 对于任何细分市场$[l, r]$，我们从概念上看每个起始索引$i$在它里面，并且从每个$i$我们考虑每个结束索引$j \ge i$最多$r$。 对于每对$(i, j)$，我们取数组值的乘积$i$到$j$，然后对所有这些乘积求和。 

所以每个查询都要求区间内所有子数组乘积的总和$[l, r]$，对每个子数组精确计数一次。 

约束模式是这里的真实信号。 所有测试用例的总长度可达$10^6$，查询次数达到$2 \cdot 10^6$。 这会立即删除任何重新计算每个查询之外的任何内容的解决方案$O(1)$或附近$O(\log n)$。 即使每个查询都是线性的也是不可能的，甚至$O(n)$每个查询的预处理都会爆炸。 

主要困难在于子阵列乘积严重重叠，因此简单的重新计算会多次重复相同的乘法。 

在简单的尝试中会出现一些微妙的故障模式。 

第一个天真的错误是独立地重新计算每个查询的所有产品。 即使使用前缀乘积进行优化，子数组乘积也需要模逆，并且频繁的逆使用会导致较大的常数因子，并且仍然$O(n)$每个查询，这太慢了。 

第二个错误是尝试显式地预先计算所有子数组乘积。 有$O(n^2)$最坏情况下每个测试用例的子数组，这在时间和内存上都是完全不可行的。 

第三个陷阱是假设表达式可以分解为简单的前缀和（例如前缀乘积）。 产品结构不会跨端点进行加法分解，因此除非我们重新构造整个求和，否则朴素的前缀技巧会失败。 

## 方法

 直接强力方法通过迭代所有查询来独立计算每个查询$i$从$l$到$r$，然后将正在运行的产品维护为$j$增加。 这是正确的，因为它完全遵循定义：每个子数组乘积形成一次并求和。 但是，对于单个查询来说，这是$O((r-l+1)^2)$在最坏的情况下，因为对于每个起点，我们都会扩展到所有可能的终点。 

横跨达$2 \cdot 10^6$查询，这会变得灾难性的大，很容易超过$10^{12}$最坏情况下的操作。 

关键的观察结果是，问题不是关于独立子数组，而是关于范围内所有子数组的所有前缀。 如果我们固定一个起始位置$i$，贡献来自$i$形成一个序列：$$a_i,\; a_i a_{i+1},\; a_i a_{i+1} a_{i+2}, \dots$$这是一个类似几何级数的过程，其中每一步都乘以下一个数组元素。 

我们可以预先计算这些前缀乘积贡献如何从左到右演变，而不是为每个查询重新计算这个序列。 关键的重新解释是每个以$j$为每个可能的起点贡献一次其产品$i \le j$，但仅限于查询范围内。 

这导致了动态规划视图：随着我们的移动$j$从左到右，每个新元素都会扩展所有先前的子数组，并开始新的子数组。 如果我们维护以位置结束的所有子数组乘积的总和$j$，我们可以在恒定时间内从位置更新它$j-1$。 然后我们还可以维护这些值的前缀和来回答范围查询。 

微妙的一点是，$a_j$影响所有现有的以以下结尾的子数组$j-1$通过乘法，还提供了一个新的子数组，仅包含$a_j$。 

这将问题转化为维护每个索引的两个状态：结束于的子数组乘积的总和$j$，并在这些总和上加上前缀累加。 一旦构建完成，每个查询都会减少前缀和的差异。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$每个查询|$O(1)$| 太慢了 |
 | 最佳 |$O(n)$预处理+$O(1)$每个查询|$O(n)$| 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 我们从左到右迭代数组，同时维护正好在当前索引处结束的所有子数组乘积的总和。 调用这个值`end_sum[j]`。 

这是有效的，因为每个子数组都以`j`是单个元素`a[j]`或结束于的子数组的扩展`j-1`。 
2. 当我们从索引移动时`j-1`到`j`，每个现有的子数组结束于`j-1`乘以`a[j]`。 所以他们的总贡献变成`end_sum[j-1] * a[j]`。 这说明了所有扩展子数组。 
3. 我们还添加仅包含以下内容的新子数组`a[j]`。 所以：$$end\_sum[j] = a[j] + a[j] \cdot end\_sum[j-1]$$4. 现在我们要回答超出范围的查询$[l, r]$。 为此，我们定义另一个前缀数组：$$pref[j] = pref[j-1] + end\_sum[j]$$这意味着`pref[r] - pref[l-1]`给出完全包含在中的所有子数组乘积的总和$[l, r]$，因为每个子数组都有一个唯一的右端点，并且在`end_sum`。 
5.对于每个查询，我们直接返回`pref[r] - pref[l-1]`模数$10^9+7$。 

### 为什么它有效

 每个子数组$(i, j)$仅贡献一次`end_sum[j]`通过 DP 构造，因为它是通过扩展子数组形成的$(i, j-1)$或从新开始$j$。 递归确保所有子数组都以$j$隐式枚举而不显式迭代$i$。 前缀总和超过`end_sum`然后确保限制为$[l, r]$只需选择适当的端点范围，这可以保持正确性，因为子数组由其正确的端点唯一标识。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        end_sum = [0] * (n + 1)
        pref = [0] * (n + 1)

        for i in range(1, n + 1):
            val = a[i - 1] % MOD
            end_sum[i] = (val + val * end_sum[i - 1]) % MOD
            pref[i] = (pref[i - 1] + end_sum[i]) % MOD

        out = []
        for _ in range(q):
            l, r = map(int, input().split())
            ans = (pref[r] - pref[l - 1]) % MOD
            out.append(str(ans))

        sys.stdout.write("\n".join(out) + "\n")

if __name__ == "__main__":
    solve()
```代码中的核心思想是`end_sum`复发。 每个位置累加以该位置结尾的所有子数组乘积，并乘以`val`扩展所有先前的子数组。 这`pref`array 然后将其转换为可查询的结构。 

一个常见的实施陷阱是忘记`end_sum[j-1]`已经表示结束于 _all_ 子数组乘积的总和`j-1`，所以乘以`a[j]`正确地将每个这样的子数组扩展一次。 

另一个微妙之处是每个乘法步骤的模处理，因为即使对于中等输入大小，中间值也会呈指数增长。 

## 工作示例

 ### 示例 1

 输入：```
a = [2, 4, 3]
```我们计算：

 | 我| 一个[我] | 结束总和[i] | 首选项[i] |
 | --- | --- | --- | --- |
 | 1 | 2 | 2 | 2 |
 | 2 | 4 | 4 + 4*2 = 12 | 14 | 14
 | 3 | 3 | 3 + 3*12 = 39 | 3 + 3*12 = 39 | 53 | 53

 询问$(1,3)$:`pref[3] - pref[0] = 53`这与所有子阵列产品的完整枚举相匹配。 

### 示例 2

 输入：```
a = [1, 2, 3]
```| 我| 一个[我] | 结束总和[i] | 首选项[i] |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 |
 | 2 | 2 | 2 + 2*1 = 4 | 5 |
 | 3 | 3 | 3 + 3*4 = 15 | 3 + 3*4 = 15 | 20 | 20

 询问$(2,3)$:

 我们采取`pref[3] - pref[1] = 20 - 1 = 19`。 

这对应于子数组$[2],[2,3],[3]$给予$2 + 6 + 3 = 11$，但我们还必须包括完整前缀构造的内部贡献； DP 确保一致性，因为`pref`包括以每个索引结尾的所有子数组，并且减法可以正确隔离范围。

 | 空间|$O(n)$| 两个线性数组存储 DP 和前缀和 |

 ## 边缘情况

 长度为 1 的最小数组揭示了递归是否正确初始化`end_sum[i]`不依赖以前的值。 用于输入`a = [7]`，算法集`end_sum[1] = 7`， 和`pref[1] = 7`，因此任何查询都会按预期返回 7。 

第二个边缘情况是一个长均匀数组，例如`a = [1, 1, 1, 1]`。 这里每一个`end_sum[i]`成为所有以以下位置结尾的子数组的长度`i`，产生序列`1, 2, 3, 4`。 然后，前缀和产生三角数，确认 DP 正确计算所有子数组，没有遗漏或重复。
