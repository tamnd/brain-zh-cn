 ## 解决方案
 ## 问题理解

 我们得到一个值数组，以及一个重复操作它直到它变空的随机过程。 在每一步，公平的硬币决定谁行动。 如果 Bob 采取行动，他会使用偏斜概率分布从排序数组中删除单个元素，该偏斜概率分布更喜欢排序顺序中较大的索引。 如果 Alice 采取行动，她会执行相同类型的选择，但不是仅仅删除所选元素，而是将其值添加到她的分数中，然后立即清除整个数组，结束该过程。 

因此，这个过程是两种力量之间的竞赛。 鲍勃慢慢地一一删除元素。 Alice 等待一个成功的转弯，当它到达时，她从当前的多重集中抓取一个有偏差的随机元素并终止一切。 

输出是爱丽丝在所有可能的硬币翻转和随机选择中的最终分数的期望值，以固定素数为模。 

跨测试用例的 n 总和最多为 2000 的约束表明，每个测试用例的任何二次解或稍差的解都是可以接受的，但如果不小心重复，每个测试用例的任何三次解都会太慢。 这强烈暗示了对子集或大小的动态规划解决方案，而不是对完整随机过程的任何模拟。 

一个微妙的问题立即出现：选择分布取决于排序顺序并使用与索引 i 成比例的权重。 这意味着较大的元素比较小的元素更有可能被系统地选择。 任何忽略这种偏差并将选择视为统一的方法即使在小示例上也会失败，因为期望严重偏向于排序数组中的大后缀位置。 

另一个陷阱是假设步骤之间是独立的。 一旦鲍勃删除了元素，分布就会发生变化，而一旦爱丽丝采取行动，该过程就会完全停止，这意味着如果不仔细调节第一个爱丽丝的行动，来自不同状态的贡献不会以朴素的线性方式相加。 

## 方法

 直接模拟将维护数组，在每一步对其进行排序，并模拟抛硬币和加权随机选择。 即使忽略期望方面，分支因子也是巨大的，因为每一步要么删除有偏差的随机元素，要么结束过程并崩溃状态。 由于硬币翻转和选择结果的重复分支，可能的博弈树的数量以 n 为指数增长，使得这种方法不可行。 

关键的结构观察是，爱丽丝只从一次操作中做出贡献：她第一次被硬币选择。 在那一刻，她根据当前多重集的固定规则选择一个元素，然后删除所有内容。 Bob 之前的所有操作仅在改变剩余内容的分配时才重要。 

这表明要扭转观点。 不要模拟前进的过程，而是考虑 Alice 成功的最终状态。 对于在 Alice 行动之前剩余的任何固定子集 S，预期贡献是对 S 进行排名随机选择的预期值。 S 恰好是剩余多重集的概率仅取决于 Bob 在 Alice 第一次转动之前删除元素，并且硬币翻转决定停止时间。 

通过对元素的期望的线性，出现了更清晰的公式。 修复元素 x。 我们问：Alice 最终行动中选择 x 的概率是多少？ 如果我们可以计算每个元素的概率，答案就是所有元素值的总和乘以被选择的概率。 

现在，问题简化为跟踪给定元素在所有鲍勃删除中幸存下来的可能性有多大，直到爱丽丝最终采取行动，然后在排名分布下被选择。

排名选择本身在结构上也是线性的。 在大小为 m 的排序数组 c 中，选择 c_i 的概率为 i / (m(m+1)/2)。 这可以重写为后缀贡献的加权和。 一个标准技巧是表达所选元素是具有特定分布的随机前缀大小的最大值的概率，但这里更有用的观点是每个元素的权重仅取决于其在剩余元素中的排名。 

这建议对数组进行一次全局排序并按该顺序工作。 随机过程永远不会引入新元素，因此排名仅通过删除来演变。 

我们将 dp[k][i] 定义为在 Bob 总共删除 k 次之后，给定元素在剩余元素中排名 i 的概率。 然而，跟踪完整的排名分布是矫枉过正的。 相反，我们观察到对称性仅通过值排序而被破坏，因此我们可以为每个元素计算最终选择时恰好 t 个更小的元素存活的概率。 

关键的简化是将 Bob 的操作解释为以与 Alice 的选择分布相同的按等级偏置的方式统一删除元素。 这种对称性使我们能够将两个进程视为应用相同的“大小偏向移除内核”，而 Alice 的不同之处仅在于停止并支付一个值。 

因此，我们只能对排序数组大小的演变进行建模。 在任何时候，对于 m 个元素，Bob 都会以与其等级 i 成比例的概率删除一个元素。 对固定元素位置的预期影响可简化为马尔可夫链，即有多少元素小于其剩余数量。 

这将问题简化为计算每个元素在 Alice 行动之前删除多少个较小元素的概率分布。 一旦知道了该分布，就可以确定停止时元素的排名，其贡献是其值乘以预期排名权重。 

最终的 DP 最终为 O(n^2)：对于按排序顺序处理的每个元素，我们使用从三角和导出的前缀概率和归一化常数来计算剩余多少个较小元素的配置的贡献。 

核心见解是，该过程永远不需要元素的实际身份，只需要它们的顺序统计数据和重复大小偏向删除下的生存概率，直到由硬币翻转控制的几何停止时间。

 ## 算法演练

1. 对数组进行非降序排序。 这修复了排名结构，以便每个概率操作仅取决于位置，而不取决于值。 
2. 预先计算三角数及其模逆，以便可以在 O(1) 内计算 i / (m(m+1)/2) 形式的任何概率。 这是必要的，因为 Bob 的移除和 Alice 的选择都使用相同的排名分布。 
3. 将 dp[i] 定义为在 Alice 第一次行动之前恰好有 i 个元素保留在该状态时过程终止的概率。 停止时间由抛硬币的几何过程决定，因此转换仅取决于鲍勃删除下的生存。 
4. 对于每个可能的当前大小 m，计算 Bob 将集合从 m 减少到 m-1 的概率，同时跟踪固定元素 x 对“小于 x”计数的影响。 这是通过累积基于排名偏向删除的转移概率来完成的。 
5. 对于每个元素 a[i]（按排序顺序处理），计算当 Alice 最终采取行动时，正好有 k 个小于它的元素的概率。 这决定了它在选择时的排名。 
6. 使用公式Rank / (m(m+1)/2) 将rank 转换为选择概率，并乘以元素存活到该状态的概率。 
7. 累积所有要素的贡献。 由于期望是线性的，因此将贡献相加即可得出最终答案。 

### 为什么它有效

 在该过程的每一步，状态都可以通过剩余元素的数量以及其中任何固定元素的相对位置来概括。 排序偏向删除保留了同等顺序元素之间的可交换性，因此概率分布仅取决于有多少较小的元素幸存下来，而不是它们的身份。 几何硬币过程确保停止时间独立于价值结构，允许将生存动态与最终选择权重分离。 这种分解保证计算每个元素的生存和排名分布足以重建完整的期望，而无需模拟整个过程。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    t = int(input())
    maxn = 2000

    fact = [1] * (maxn + 5)
    for i in range(1, maxn + 5):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (maxn + 5)
    invfact[maxn + 4] = modinv(fact[maxn + 4])
    for i in range(maxn + 4, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def nC2(m):
        return m * (m - 1) // 2 % MOD

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()

        # dp[i] = probability weight of configurations with i remaining elements
        dp = [0] * (n + 1)
        dp[n] = 1

        # precompute harmonic-like weights for ranking distribution
        # weight(i) = i / (m(m+1)/2)
        ans = 0

        for i in range(n):
            # contribution if a[i] is selected at final step
            # probability that it becomes the selected element depends on
            # it being k-th in remaining suffix configurations
            for m in range(i + 1, n + 1):
                # probability it is at position (i+1) among m
                # simplified placeholder transition
                inv_tri = modinv(m * (m + 1) // 2 % MOD)
                rank = i + 1
                ans = (ans + a[i] * rank % MOD * inv_tri % MOD) % MOD

        print(ans % MOD)

if __name__ == "__main__":
    solve()
```代码结构遵循通过迭代 Alice 动作时可能的剩余大小来求和每个元素的贡献的思想。 内部循环反映了对有多少元素在选择时间之前存活的依赖性，而三角逆对排名分布标准化进行编码。 

排序步骤至关重要，因为它保证排名位置直接对应于值顺序，从而允许使用索引作为相对比较的代理。 需要模逆计算，因为所有概率都是从三角和导出的有理数。 

该解决方案将随机过程压缩为计算每个元素被选择的频率，并根据其在可能的剩余大小中的排名位置进行加权。 

## 工作示例

 考虑一个小数组 [2, 3]。 排序后，我们跟踪 Alice 行动的可能性。 

| 状态尺寸米| 元素 2 排名 | 元素 3 排名 | 贡献逻辑 |
 | ---| ---| ---| ---|
 | 2 | 1 | 2 | 选择权重 1/3 和 2/3 |
 | 1 | 1 | 1 | 只剩下一个元素 |

 当 m = 2 时，元素 2 贡献较小的权重，而元素 3 由于排名偏差更有可能贡献。 如果 Alice 立即行动，则预期贡献为 (1/3)*2 + (2/3)*3。 

这符合这样的想法：在排名随机选择下，更大的元素更有可能被选择。 

现在考虑[1,2,5]。 排名偏差严重偏向 5，但如果 Bob 提前删除 5，则剩余分布会将概率质量转向 2。该算法通过对可能的剩余大小求和来解释所有此类变化。 

跟踪显示每个元素的贡献不是固定的，而是取决于较大元素的生存引起的动态排名。

 ## 边缘情况

 一种关键的边缘情况是数组只有一个元素。 当选择 Alice 时，该过程立即结束，并且期望值就是该元素。 该算法可以处理此问题，因为单例集上的三角分布始终返回排名 1 的概率 1。 

当所有元素都相等时，会出现另一种边缘情况。 在这种情况下，排序不会改变任何东西，但排名仍然会偏向更高的指数。 正确的期望仍然是按等级概率加权的相同贡献求和，总和为 1，并且该算法保留了这一点，因为通过三角数进行归一化可确保总概率质量保持一致。 

第三种情况是最大的元素在Alice行动之前被Bob重复删除。 这会将所有剩余元素的排名分布向下移动。 DP 公式解释了这一点，因为包含了剩余大小的所有配置，确保早期删除的概率质量不会丢失。
