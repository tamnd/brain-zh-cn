 ## 解决方案
 ## 问题理解

 我们有一个由采访者组成的小型系统，他们以小组的形式反复进行采访。 每次面试都包含以下内容：`z`不同的面试官，每个面试官最多只能参与`y`每天面试。 有`x`面试官总数，任务是安排尽可能多的此类面试，同时尊重每个面试官的能力限制。 

有效的输出是一个组列表，其中每个组是一组`z`不同的采访者 ID。 每个小组代表一次进行的采访。 该限制纯粹在于每个采访者 ID 在所有组中可以出现的次数。 

从结构的角度来看，这是一个有界组合堆积问题。 我们正在尝试包装尽可能多的尺寸-`z`尽可能将子集划分为多重集合`x`每个元素都有容量的元素`y`。 

限制非常小：`x, y, z ≤ 10`。 这立即告诉我们，可能的不同采访组的数量最多是`C(10, z)`，最多为 252。即使我们枚举所有组合并模拟使用计数，状态空间仍然很小。 这强烈表明贪婪构造甚至系统枚举就足够了。 

出现微妙的边缘情况时`x < z`。 在这种情况下，根本不存在有效的组，因为我们无法形成一组`z`不同的采访者。 另一个边缘情况是当`y = 0`，这迫使答案为零，无论`x`和`z`。 没有明确保护这些情况的简单实现可能会尝试构建组并遇到无效索引或产生不可行的计划。 

## 方法

 强力解释将处理每个可能的大小子集`z`作为候选人面试，并尝试选择最大数量的此类子集，同时确保面试官不会超出使用范围`y`。 这本质上是超图上的最大打包问题，直接搜索将尝试子集的组合。 

虽然正确性很容易推理，但当我们考虑每个子集都可以选择或不选择时，就会发生组合爆炸，从而导致粗略的结果`2^(C(x, z))`的可能性。 虽然`x ≤ 10`，这仍然导致`2^252`在最坏的情况下，这是完全不可行的。 

关键的观察是我们不需要任何全局意义上的最优子集选择。 我们只需要产生一个可行的结构，使组的数量最大化。 由于所有采访者都是对称的，因此我们可以均匀地分配参与。 自然的结构是循环采访者并始终选择连续的规模组`z`，循环环绕，同时跟踪每个采访者被使用的次数。 

因为`x`很小并且`y`很小，我们可以贪婪地一个接一个地建立组，总是选择下一个可用的组`z`仍有剩余能力的采访者。 如果我们维护一个指针并轮换采访者 ID，我们就可以确保公平性并避免过度使用任何单个参与者。 这种构建一直持续到无法形成有效的组为止。 

这样做的原因是任何有效的计划仅受总容量的限制`x * y`，每次采访正好消耗`z`容量单位。 因此上限是`floor(x * y / z)`，并且贪婪循环构造在小的约束下自然地接近这个界限。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集搜索 | O(2^(x 选择 z)) | O(x 选择 z) | 太慢了 |
 | 贪心循环构造| O(x * y * z) | O(x) | 已接受 |

 ## 算法演练

 我们迭代地构建访谈，同时跟踪每个访谈者的剩余能力。 

1.初始化一个数组`used[i] = 0`对于所有面试官`i`，代表他们参加了多少次采访。这确保我们可以执行限制`y`。 
2. 维护当前指针`p`面试官来自`1`到`x`。 该指针有助于均匀分配使用，而不是重复从同一子集中进行选择。 
3. 如果可能，尝试组建一个访谈小组：

 我们向前扫描`p`并选择下一个`z`不同的采访者`used[i] < y`。 

此扫描步骤确保我们始终构建一个有效的组而不违反约束，因为我们明确过滤了精疲力尽的采访者。 
4. 如果在任何时候我们找不到`z`可用的采访者，停下来。 这意味着无法进行进一步的有效采访。 
5. 成组后，递增`used[i]`对于每个选定的采访者，将其添加到答案列表中，并将指针向前移动以继续公平分配。 
6. 继续，直到达到终止条件。 

### 为什么它有效

 在每一步中，该算法仅选择具有剩余能力的采访者，因此不会违反任何约束。 循环扫描确保如果存在可行的组，它最终会被发现，因为可以通过在一个小的固定宇宙上轮换来到达可用采访者的所有组合。 由于容量单调减少，该过程必须终止，并且当终止时，在约束下无法形成有效的组，这意味着在这个有界设置中的贪婪策略下构造是最大的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x, y, z = map(int, input().split())
        
        if z > x or y == 0:
            print(0)
            continue
        
        used = [0] * (x + 1)
        ans = []
        p = 1
        
        while True:
            group = []
            start = p
            i = start
            scanned = 0
            
            while scanned < x and len(group) < z:
                if i > x:
                    i = 1
                if used[i] < y:
                    group.append(i)
                i += 1
                scanned += 1
            
            if len(group) < z:
                break
            
            for v in group:
                used[v] += 1
            
            ans.append(group)
            p += 1
            if p > x:
                p = 1
        
        print(len(ans))
        for g in ans:
            print(*g)

if __name__ == "__main__":
    solve()
```该解决方案为每个采访者维护一个使用计数器，并通过循环扫描采访者 ID 来构建每个组。 内循环确保我们准确收集`z`具有剩余能力的不同采访者。 指针`p`每组之后都会发生变化，这样我们就可以避免重复选择相同的早期索引。 

一个微妙的实现细节是索引的显式环绕`i`。 如果没有它，当扫描到达面试官名单的末尾时，就会错过有效的候选人。 另一个重要的细节是当少于`z`可以找到候选者，因为任何进一步的尝试也会由于容量的单调耗尽而失败。 

## 工作示例

 ### 示例 1

 输入：```
3 2 2
```我们有3位面试官，每人可以出现两次，每次面试使用2个人。 

| 步骤| 指针p | 选定的组 | 使用次数 |
 | --- | --- | --- | --- |
 | 1 | 1 | [1,2]| 1:1、2:1、3:0 |
 | 2 | 2 | [2,3]| 1:1、2:2、3:1 |
 | 3 | 3 | [3,1]| 1:2、2:2、3:2 |

 在第 4 步，无法形成规模为 2 的小组，因为所有采访者都已达到容量 2。构造在 3 次采访时停止。 

这表明循环扫描均匀地分配了负载并实现了充分的容量利用。 

### 示例 2

 输入：```
4 1 3
```每个采访员只能出现一次，每组需要3名采访员。 

| 步骤| 指针p | 选定的组 | 使用次数 |
 | --- | --- | --- | --- |
 | 1 | 1 | [1,2,3]| 1:1、2:1、3:1、4:0 |
 | 2 | 2 | [2,3,4]| 1:1、2:2（无效）|

 此时，如果重新使用采访者 2 和 3，采访者 2 和 3 已经超出容量，因此不存在第二个有效组。 算法在 1 次采访后停止。 

这演示了即使存在许多组合，容量约束也如何直接限制组的数量。

 ## 边缘情况

 当`z > x`，算法立即返回零。 例如，使用输入`x=2, z=3`，任何扫描都无法收集到足够多的不同采访者，因此内部循环总是失败，我们会停止而不产生组。 

什么时候`y = 0`，每个面试官从一开始的能力就为零。 扫描循环永远不会添加任何候选者，所以`group`永远达不到尺寸`z`，算法立即终止并输出`0`。 

什么时候`x = z`，每次有效的访谈都必须使用所有访谈员。 该算法最多会产生`y`相同的完整组，因为每个采访者在迭代中都是统一的。 这与每轮均匀使用所有可用容量的最佳包装相匹配。
