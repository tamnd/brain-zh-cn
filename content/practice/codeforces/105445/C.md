 ## 解决方案
 ## 问题理解

 我们得到一个数组，并要求计算由所有连续子数组构建的非常大的嵌套总和。 对于每个起始索引`i`，我们查看每个结束索引`j ≥ i`，计算子数组的乘积`a[i] ... a[j]`，然后对所有可能的值求和`(i, j)`对。 

因此，数量本质上是每个子数组贡献的总和，其中每个子数组贡献一次其乘积。 

即使在这个简单的版本中，输入也可以在测试用例中包含多达一百万个元素，因此任何显式枚举子数组或从头开始重新计算产品的解决方案都将立即失败。 子数组的二次方数量已经给出了大约`5e11`最大尺寸的操作，如果不小心重用，每个乘积计算都会添加另一个线性因子。 

主要困难在于乘积以乘法增长，但所需的总和是在所有子数组上相加的，因此我们需要一种方法来跨重叠子数组重用部分结构。 

当所有值都为`1`。 在这种情况下，每个子数组乘积都是`1`，答案就变成了子数组的总数，即`n(n+1)/2`再次对起点进行求和，在朴素的推理中产生了类似立方体的增长模式。 这正是暴力模拟崩溃的地方。 

另一个边缘情况是接近的大值`1e9`。 如果我们不小心，不进行模归约的直接乘法就会溢出 64 位整数，甚至模运算也需要仔细排序以避免重新计算开销。 

## 方法

 暴力法很简单。 对于每个起始索引`i`，我们扩展`j`从`i`到`n`，维持运行产品`a[i]...a[j]`，并将其累积成答案。 这正确匹配定义并且有效，因为每个子数组都被访问一次。 

然而，这种方法会重新计算或重复更新每个产品`(i, j)`对，导致`O(n^2)`每个测试用例的乘法。 总共有`n`最多`10^6`，这变得太慢了。 

关键的观察是，我们正在对所有子数组的贡献求和，并且每个元素以结构化方式参与许多子数组。 我们可以不考虑子数组，而是反转视角，将每个位置的贡献视为前缀动态累积的一部分。 

如果我们修复一个端点`j`，每个子数组结束于`j`可以看作是扩展结束于的子数组`j-1`乘以`a[j]`，然后添加单元素子数组`[j]`。 这建议维持两个滚动量：所有子数组乘积的总和结束于`j`，以及全局答案。 

这将问题转化为线性递归，其中每一步都会更新所有先前的贡献`a[j]`，但我们没有显式更新所有先前的状态，而是重用了以下事实：所有子数组的总和以`j-1`已经对他们的产品进行了编码。 将该总和乘以`a[j]`自动转换每个结尾的子数组`j-1`进入其扩展版本，结束于`j`。 

因此，转换变成每个位置的局部且恒定的时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了 |
 | 后缀贡献的最优 DP | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从左到右处理数组，同时维护一个滚动值，该值表示以当前索引结尾的所有子数组乘积的总和。 

1. 初始化变量`end_sum`存储以当前位置结尾的所有子数组的乘积之和。 初始化`answer`来积累最终的结果。 
2. 从索引处迭代数组`0`到`n-1`。 
3.就位`j`，每个子数组结束于`j`是一个仅包含以下内容的新子数组`a[j]`，或结束于的子数组的扩展`j-1`乘以`a[j]`。 这给出了重现`end_sum = a[j] + end_sum * a[j] (mod M)`。 

这样做的原因是将所有先前的结束子数组乘以`a[j]`正确地扩展它们而不丢失任何结构。 
4.添加`end_sum`进入全球`answer`。 这捕获了所有以`j`。 
5. 继续直到数组末尾。 决赛`answer`是所有子数组的总和。 

### 为什么它有效

 在每个索引处`j`,`end_sum`恰好等于右端点为的所有子数组的乘积之和`j`。 这是归纳保留的，因为每个这样的子数组要么从`j`或者是通过扩展结束于的子数组而形成的`j-1`。 由于乘法分布于加法，因此将所有先前的子数组扩展`a[j]`相当于将他们的总贡献乘以`a[j]`，并添加单例子数组完成集合。 因为每个子数组都有一个右端点，所以对所有子数组求和`end_sum`value 恰好覆盖每个子数组一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        
        end_sum = 0
        ans = 0
        
        for x in a:
            end_sum = (x + end_sum * x) % MOD
            ans = (ans + end_sum) % MOD
        
        # q = 1 and l=1, r=n always
        input()  # consume query line
        print(ans)

if __name__ == "__main__":
    solve()
```实现中的关键状态是`end_sum`，它表示以当前索引结尾的所有子数组。 每次更新都会将先前的状态乘以当前元素，然后添加新的单元素子数组。 第二个累加器`ans`汇总所有端点的贡献。 

输入始终提供覆盖整个数组的单个查询，因此我们只需为每个测试用例计算一次全局结果，并在读取它们后忽略查询边界。 

一个常见的陷阱是忘记递归在每一步都应用模数。 如果乘法后没有模数约简，即使对于编译上下文中的 Python 性能考虑，中间值也会变得太大。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个元素都被处理一次并不断更新 |
 | 空间| O(1) | O(1) | 仅维护两个运行变量 |

 这些约束允许最多一百万个元素，因此每个测试用例的线性扫描是最佳的。 该解决方案仅对每个元素执行恒定数量的算术运算，完全在 2 秒的限制之内。

 ## 边缘情况

 对于全部为 1 的数组，可以说`a = [1, 1, 1]`，递归给出`end_sum`价值观`1, 2, 3`，以及最终答案`6`。 这符合以下事实：正好有六个子数组，每个子数组都有贡献值`1`。 该算法正确地累积它们，因为每个扩展都保留了价值。 

对于单个大元素，例如`a = [10^9]`，递归产生`end_sum = 10^9`并回答`10^9`。 由于只有一个子数组，因此不会发生溢出或隐藏交互，模运算直接捕获结果。 

对于像这样的严格递增数组`[1, 2, 3, 4]`，每一步将所有先前的子数组贡献乘以新元素并添加新的单例。 跟踪显示，没有子数组被重复计算，因为每个子数组都唯一锚定在其右端点，从而确保迭代之间不相交的计算。
