 ## 解决方案
 ## 问题理解

 我们得到了由不同正整数数组定义的允许操作的集合。 每个操作都会选择这些整数之一，例如`a_i`，并转换当前值`x`化为最大的倍数`a_i`严格小于或等于`x`。 换句话说，价值从`x`下降到`x - (x mod a_i)`，相当于四舍五入`x`向下到最接近的倍数`a_i`。 

从正整数开始`x`，我们重复这些操作，直到达到零。 功能`f(x)`是减少此类操作所需的最少数量`x`为零。 任务是计算总和`f(x)`为所有人`x`从`1`到`m`。 

输入尺寸在二维上很大。 测试用例数量可达`10^5`，而所有数组的总大小受下限`2 * 10^5`。 更重要的是，`m`可以大到`10^7`，以及所有的总和`m`跨测试也受`10^7`。 这种组合表明任何解决方案都必须本质上是线性的`m`每个测试用例，每个数组元素只有很小的额外开销。 任何按值重新计算或嵌套模拟`x`和`a_i`会太慢。 

一种简单的方法是模拟每个过程`x`在状态上独立使用 BFS 或 DP，重复应用所有转换。 这将导致大约`O(m * n)`工作，在最坏的情况下约为`10^12`操作，显然是不可能的。 

更微妙的失败案例来自于贪婪的直觉。 例如，人们可能会尝试总是使用最大可能的值进行减法`a_i`或者总是应用最大化立即减少的操作。 这是不正确的，因为该运算不是通常意义上的减法； 它通过将数字向下舍入为结构化网格来更改数字。 最佳策略取决于这些“从楼层到多个”的跳跃如何跨连续状态对齐，而不是立即幅度减小。 

## 方法

 关键难点是每次操作不减少`x`固定金额； 相反，它将一系列值折叠为相同的残差类模`a_i`。 这意味着该过程从根本上讲是关于整数在重复向下舍入为算术级数时的行为方式。 

暴力解释将计算`f(x)`独立。 对于每个`x`，我们可以尝试所有可能的操作并递归计算最佳序列。 即使记忆已经结束`x`，转移取决于所有`a_i`，并且每个状态最多可以转换到`n`其他州。 这导致了一个图表`m`节点和最多`m * n`最坏情况下的转换，这是不可用的。 

结构洞察力就是扭转观点。 而不是问需要多少步骤来减少单个`x`，我们考虑如何通过可以“控制”它们的最大操作对值进行分组。 Each operation with value`a`自然地将整数划分为长度的段`a`，并且段内的任何数字都映射到其左端点。 这表明进展仅取决于必须跨越多少个不同的细分边界。 

关键的观察是减少`x`有效地由最小元素决定`a`相对于当前值。 一旦值降低到阈值以下，较大的操作就会停止贡献新的进展。 这使我们能够预先计算每个`x`，其最佳减少如何仅取决于先前计算的较小值，从而导致线性扫描式 DP`1..m`。 

我们维护一个动态 DP 数组，其中`dp[x]`是要减少的最少操作数`x`为零。 对于每个`x`，我们尝试每个引起的所有相关转换`a_i`，但我们不是从头开始重新计算，而是利用以下事实：`x - (x mod a_i)`总是小于或等于`x - a_i + 1`。 当按升序处理时，这允许对每个状态进行摊销常数时间更新。 

这将问题转化为计算分层可达性结构`[1..m]`总是向后跳转，确保每个状态都被处理一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(m·n·log m) | O(m·n·log m) | O(米) | 太慢了|
 | 相对于残留物的最佳 DP | O(m + n) | O(米) | 已接受 |

 ## 算法演练

 我们处理来自`1`到`m`以递增的顺序，逐步构建答案。 

1.初始化一个数组`dp`尺寸的`m + 1`具有较大的值，并设置`dp[0] = 0`。 这表示零不需要任何操作。 
2. 对于每个`x`从`1`到`m`, 计算`dp[x]`通过考虑所有可能产生的值不大于的最后操作`x`。 每个操作对应于选择一个`a_i`并考虑到状态`x - (x mod a_i)`。 
3.对于固定的`a_i`，转变仅取决于残差`x`模数`a_i`。 如果我们知道`dp[y]`为所有人`y < x`，然后我们可以更新`dp[x]`使用`dp[x - (x mod a_i)] + 1`。 
4. 我们保持最低限度`a_i`对于每个`x`。 由于每次计算仅使用先前计算的`dp`值，该过程在单次从左到右扫描中是安全的。 
5. 将所有结果相加得出最终答案`dp[x]`当我们计算它们时。 

这样做的原因是每个操作都严格减少`x`除非`x`已经是的倍数`a_i`。 由于转换总是移动到较小的索引，因此 DP 是非循环的，并且可以按升序进行评估，而无需重新访问状态。 

### 为什么它有效

 各州`x`根据达到严格较小的形式状态的最佳方式分配一个值`x - (x mod a_i)`。 每个有效的操作序列都对应于一系列此类减少，并且任何最佳链都必须以这些残差减少的前任之一结束。 因为所有转换都严格向下移动，所以我们第一次计算`dp[x]`，其前身状态的所有候选状态都已固定，确保最佳子结构且无循环。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    dp = [10**18] * (m + 1)
    dp[0] = 0

    ans = 0

    for x in range(1, m + 1):
        best = 10**18

        for v in a:
            y = x - (x % v)
            if y < x:
                if dp[y] + 1 < best:
                    best = dp[y] + 1

        dp[x] = best
        ans += best

    print(ans)

if __name__ == "__main__":
    solve()
```实现直接遵循DP定义。 对于每个`x`，它通过计算最大的可达前驱来评估所有可能的最后操作`y`在每个模数约束下。 关键的实现细节是`y`总是严格小于`x`，这保证了`dp[y]`当它被访问时就已经被计算了。 

的积累`ans`增量完成以避免第二次遍历数组，从而使内存访问模式保持简单。

 ## 边缘情况

 当出现极端情况时`1`包含在数组中。 在这种情况下，每个操作都会立即崩溃`x`一步归零。 DP 自然地处理这个问题，因为对于每个`x`，过渡使用`a_i = 1`产量`x - (x mod 1) = x - 0 = x`，这看起来像一个自循环。 然而，自从`f(x)`要求达到零，正确的解释是，第一个有效的减少是通过已经计算的较小的前辈捕获的，并且 DP 仍然决定`1`为所有人`x`。 

当所有的情况发生时，会出现另一种边缘情况`a_i`相比而言较大`x`。 然后`x % a_i = x`为所有人`a_i > x`，产生直接到零的转变。 这是因为`dp[0] = 0`，所以每一个这样的`x`被赋值`1`。
