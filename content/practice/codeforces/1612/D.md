 ## 解决方案
 ## 问题理解

 给定一对整数$a$和$b$，和另一个整数$x$。 我们可以重复更换其中任何一个$a$或者$b$与绝对差异$|a - b|$。 任务是确定在进行一定数量的这些操作之后是否可以$a$或者$b$等于$x$。 我们有多个独立的测试用例，每个都有自己的$a, b, x$。 

约束条件允许$a, b, x$去到$10^{18}$，并且最多可以有$10^4$测试用例。 这使得任何模拟所有操作的方法都明显不可行，因为步骤数量可能非常大。 我们需要一种直接处理数字属性的方法$a$和$b$，而不是生成所有可能的操作序列。 

当以下情况出现时，会出现一个关键的、不明显的边缘情况：$a = b$。 这里，$|a-b| = 0$，因此任何后续操作都不会产生除当前对和零之外的数字。 例如，如果$a = b = 30$和$x = 30$，答案是肯定的，但是如果$x = 15$，则为 NO，因为该对只能达到 0，而不能达到 15。 

另一个微妙的情况是当$x$大于任一$a$或者$b$。 例如，$a = 40, b = 50, x = 90$。 这些运算只能减少数字，所以如果$x > \max(a, b)$，答案立即是否定的。 尽早认识这些约束可以防止不必要的计算。 

## 方法

 暴力解决方案很简单：以所有可能的方式重复应用这两个操作，跟踪生成的每个新对，直到$x$被发现或序列稳定。 这是正确的，因为该问题允许两个操作的任意顺序。 这种方法的问题在于，对于大$a, b$可以生成的不同对的数量是巨大的，可能高达$10^{18}$，这是完全不可行的。 

最佳解决方案的关键见解来自于观察操作模拟计算最大公约数的欧几里得算法。 每次我们将一个数字替换为$|a-b|$，我们正在走向一个更小的对，其差异是原始的线性组合$a$和$b$。 具体来说，通过这些操作可到达的任何数字都必须满足$x \le \max(a, b)$和$x \equiv a \pmod{\gcd(a, b)}$。 这是因为欧几里德算法保证了重复应用所产生的数字序列$|a-b|$最终将产生所有倍数$\gcd(a, b)$小于或等于$\max(a, b)$。 

因此，我们可以直接检查两个条件，而不是模拟操作：$x \le \max(a, b)$和$x \% \gcd(a, b) == a \% \gcd(a, b)$。 如果两者都成立，则该对是$x$-魔法。

 ## 算法演练

 1.读取测试用例数量$t$。 
2. 对于每个测试用例，读取整数$a, b, x$。 
3. 计算$g = \gcd(a, b)$。 这捕获了通过操作可到达的所有数字的步长。 任何可到达的数字必须等于$a$模数$g$。 
4. 检查是否$x \le \max(a, b)$。 如果不是，则操作无法达到更大的数字，因此打印 NO 并继续。 
5. 检查是否$x \equiv a \pmod{g}$。 如果属实的话，$x$可达； 否则，就不是。 相应地打印“是”或“否”。 

为什么有效：类似欧几里得的运算保留了该对的最大公约数，并且最大值永远不会增加。 因此，任意数$x$可达到的值必须小于或等于当前最大值，并且必须与原始数字对 GCD 取模一致。 这两个简单的检查完全捕获了可到达的数字集。 

## Python 解决方案```python
import sys
import math
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, x = map(int, input().split())
    g = math.gcd(a, b)
    if x <= max(a, b) and (x % g == a % g):
        print("YES")
    else:
        print("NO")
```代码首先读取所有测试用例。 关键的计算是`math.gcd(a, b)`，这使得我们可以直接检查模块化条件而不是模拟操作。 检查`x <= max(a, b)`确保我们永远不会尝试达到比当前对更大的数字，并且`x % g == a % g`通过欧几里德模式保证可达性。

 ## 边缘情况

 如果$a = b = x$，算法正确返回 YES 因为`x <= max(a,b)`和`x % g == a % g`琐碎地持有。 为了$x > \max(a, b)$，它会立即正确返回 NO。 当数字非常大时，GCD 计算可以有效地处理它们，模运算可以保证正确性而不会溢出。
