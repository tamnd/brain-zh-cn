 ## 解决方案
 ## 问题理解

 我们有几个独立的地下城运行。 每次运行都由一系列级别组成，在每个级别我们必须做出一个选择：要么清除级别并获得其上写的值，要么跳过连续的级别块并支付等于我们跳过的级别数的惩罚。 

重要的微妙之处在于，“跳过”并不以通常的方式与单个级别的决策相关联。 它是一种分段操作，可以从任何位置开始应用，并且一次涵盖多个级别。 在跳过时，我们仍然在概念上超越这些级别，但无论基础值是什么，每个跳过的级别都会失去一分。 

因此，任务是将数组划分为“单独求解”和“整体跳过”的交替段，其中跳过的段贡献等于其长度的线性负成本，而求解的位置贡献其自己的值。 

输出是可达到的最大总分。 

这些约束足够严格，任何对子数组的二次或三次推理都会失败。 测试用例的级别总数高达 200,000，因此我们需要一种每个测试用例都是线性或接近线性的方法。 任何涉及尝试所有段边界或对索引对进行动态编程的操作都会太慢。 

一个常见的失败案例来自于将跳过操作误解为每个索引的本地操作，而不是每个段的全局操作。 例如，如果假设在索引 i 处跳过仅影响 i，则可能会错误地得出答案只是正值之和，而当长期负运行可以作为一组跳过时，这是错误的。 

另一个微妙的情况是所有值都是负数。 一个天真的解决方案可能认为跳过所有内容是最佳的，但跳过会产生等于长度的成本，这仍然会产生负总数，因此有时选择单个最小负元素会更好。 

## 方法

 暴力解释试图决定，对于每个片段，是否将其拆分为单独的解决方案或用跳过操作替换它。 这导致将数组的所有分区探索为段，并为每个段决定其模式。 这种分区的数量随着 n 呈指数增长，因为 i 和 i+1 之间的每个边界都可以被切割或不被切割，并且每个段也有第二个决策。 即使进行了修剪，当 n 超过非常小时时，这很快就会变得不可行。 

关键的观察结果是，跳过长度为 L 的段相当于为该段中的每个元素添加 -1 的常数成本。 这使得跳过操作可以分布在各个位置上，这意味着我们实际上根本不需要对段进行推理。 每个位置 i 要么贡献 a_i（如果我们解决它），要么贡献 -1（如果我们选择将其作为某些跳过段的一部分跳过）。 

一旦看到这一点，结构就会大大简化。 每个索引独立地在两个固定值之间做出选择：取 a_i 或取 -1。 跳过的段性质变得无关紧要，因为任何跳过位置的分组仍然与单独处理它们相同的总成本。 

因此，问题简化为每个元素的最大选择：对于每个 i，我们选择 max(a_i, -1)。 将这些选择相加即可得到全局最优值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解段分区| 指数| O(n) | 太慢了|
 | 每个元素的贪婪选择 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 对于每个测试用例，读取代表级别奖励的值数组。 目标是计算在独立的每个位置决策下可达到的最佳总分。 
2. 将累加器初始化为零。 该变量将通过汇总每个级别的最佳贡献来存储最终分数。 
3. 迭代数组中的每个值 a_i。 此时，我们考虑在任何有效策略中处理此位置的两种方式。 
4. 计算解决该关卡的贡献，即a_i。 
5. 计算有效跳过它的贡献，每层成本为-1。 
6. 将这两个值中较大的一个添加到累加器中。 此步骤抓住了这样一个事实：任何全局最优策略都必须在每个位置局部选择更好的选项，因为跳过成本不依赖于分组结构。 
7. 处理完所有位置后，输出累加器作为测试用例的答案。 

### 为什么它有效

 关键的属性是跳跃操作在位置上进行加法分解。 任何长度为 L 的跳过段都准确地贡献 -L，无论其内部如何划分。 这消除了不同指数决策之间的任何依赖性。 一旦依赖性消失，最优的全局解决方案必须由独立的最优局部决策组成，因为改变一个位置的选择不会影响任何其他位置的贡献。 这就消除了将决策耦合到各个部分所带来的任何好处。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ans = 0
        for x in a:
            if x > -1:
                ans += x
            else:
                ans += -1
        
        print(ans)

if __name__ == "__main__":
    solve()
```代码独立处理每个测试用例，这是必要的，因为它们之间没有交互。 在每个测试用例中，它会在数组上迭代一次，并对每个元素应用简单的比较。 

关键的实现细节是与 -1 的阈值比较。 任何大于 -1 的值都值得直接采用，而任何小于或等于的值最好用跳过等效成本替换。 这避免了任何分段跟踪或动态编程的需要。

def run(inp: str) -> str:

 ## 边缘情况

 一个完全负的数组，例如`[-5, -2, -3]`证明该算法从不尝试通过跳过所有内容来“逃逸”，因为跳过每个元素仍会累积 -1。 计算变成与 -1 的三个比较，为每个位置生成 -1，最终总和为 -3。 

完全正数组，例如`[1, 2, 3, 4]`表明该算法始终选择实际值，因为每个值都大于 -1。 运行总和成为数组总和，这符合直观的最佳策略。 

混合情况，例如`[ -1, 10, -5, 2, -1 ]`表明只有低于或等于 -1 的元素才会被 -1 替换，而强阳性保持不变，最终结果反映了每个位置的独立决策，没有任何耦合效应。
