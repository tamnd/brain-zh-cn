 ## 解决方案
 ## 问题理解

 我们有一个有源的定向流网络`1`和下沉`n`。 

第一个`k`边缘很特殊。 他们的能力不是固定的。 每个查询都会为每个特殊边分配一个容量，而所有其他边则保留其原始容量。 

对于每个查询，我们必须输出节点的最大流量`1`到节点`n`。 

乍一看，这看起来像是一个动态最大流量问题。 不幸的是，最多有`2 · 10^5`查询，因此每次更新后重新计算最大流是完全不可能的。 

这些限制是非常不寻常的。 该图本身相当大，最多可达`10^4`顶点和`10^4`边缘，这已经使得单个最大流计算变得非常重要。 然而，仅`k ≤ 10`边缘不断变化。 

那个微小的值`k`这就是问题的全部要点。 

另一个关键的观察是，每种特殊能力最多是`25`。 这个小界限允许我们在预处理所有残差网络的同时逐步更新残差网络`2^k`的可能性。 

一个常见的错误是认为特殊能力本身定义了国家。 他们没有。 每个查询可能包含以下任意值`0`到`25`，所以有`26^k`可能的分配，太多而无法直接预处理。 

另一个容易犯的错误是枚举特殊边的子集并为每个子集运行新的最大流。 只有`1024`子集，但图上的每个最大流`10^4`顶点和边是昂贵的。 独立完成这件事仍然太慢了。 

考虑这个小例子：```
1 -> 2 (special)
2 -> 3 (capacity 5)
```如果特殊边有容量`7`，答案是`5`。 

最小切割选择有能力的边缘`5`，不是特殊边。 任何独立于网络其余部分处理特殊边的解决方案都将在这里失败。 

另一个重要的边缘情况是特殊边缘完全不相关的情况。```
1 -> 2 (capacity 10)
1 -> 3 (special)
2 -> 4 (capacity 10)
3 -> 4 (capacity 10)
```无论分配给特殊边缘什么容量，答案都已经是`10`。 正确的解决方案必须允许忽略每个特殊边缘的最小切割。 

## 方法

 暴力解决方案很简单。 

对于每个查询，将给定容量分配给特殊边并从头开始运行最大流算法。 

最大流-最小割定理保证了正确性。 问题在于复杂性。 高达`2 · 10^5`查询，即使是非常快的 maxflow 实现也变得毫无希望。 跑步迪尼克`200000`图表上的时间`10^4`边缘超出时间限制几个数量级。 

关键的观察来自于视角的转换。 

不要考虑最大流量，而是考虑最小削减。 

对于特定的最小切割，每个特殊边缘只有两种可能性。 

切口要么包含该特殊边缘，要么不包含。 

由于只有`k ≤ 10`特殊的边，只有`2^k ≤ 1024`可能的模式。 

假设我们修复一个子集`T`需要属于切割的特殊边缘。 

对于边`T`，我们将直接支付他们的查询能力。 

对于外部特殊边缘`T`，禁止使用它们。 我们可以通过赋予他们有效的无限能力来强制执行这一点。 

转换后，剩余的最小割值仅取决于原始图结构，而不取决于查询。 

这允许我们预先计算特殊边的每个子集的值。 

剩下的挑战是计算所有`2^k`有效地陈述。 

关键的技巧是相邻子集恰好有一个特殊边不同。 我们计算所有子集的残差网络。 当多一条特殊边变得“不可切割”时，我们只添加一条容量边`25`。 

由于每个特殊能力最多`25`，该边引入的额外流量也最多为`25`。 一些 Ford-Fulkerson 增强就足以更新答案。 这避免了为每个子集重新运行完整的最大流。 

预先计算所有子集值后，每个查询都变成简单的最小值`1024`州。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(q · MaxFlow)`|`O(m)`| 太慢了|
 | 最佳|`O(MaxFlow + 2^k · 25 · m + q · 2^k)`|`O(2^k · m)`| 已接受 |

 ## 算法演练

 让`FULL = (1 << k) - 1`。 

对于一个子集`S`， 定义：`f[S] = minimum cut value when special edges in S are forbidden from appearing in the cut, and all other special edges are already considered cut.`等效地：

 如果一条特殊边属于`S`, 赋予其容量`INF`。 

如果它不属于`S`，将其完全删除。 

价值`f[S]`仅取决于图并且可以预先计算。 

对于具有容量的查询`w[i]`， 定义：`cost[M] = sum of capacities of special edges in M`。 

然后，切割图案对应于选择切割哪些特殊边缘。 

如果`M`是切割使用的特殊边的集合，其余特殊边禁止进行切割。 

因此：`answer = min( cost[M] + f[FULL xor M] )`### 1. 构建基础图

 忽略所有特殊边缘。 

运行一项普通的最大流量计算。 

结果值为`f[0]`。 

存储残差网络。 

### 2.枚举所有子集状态

 通过增加 popcount 来处理子集。 

选择一位`b`从子集：```
parent = S without bit b
```残差网络`parent`是已知的。 

### 3.添加一个新的特殊边缘

 从残差网络`parent`,插入特殊边`b`有能力`25`。 

使用`25`而不是无穷大就足够了。 

如果超过`25`流量单位需要通过该边缘，那么切割边缘本身的成本永远不会超过`25`，所以这样的切割永远不可能是最佳的。 

### 4. 重新增强流程

 从父级的残差网络开始，运行小型 Ford-Fulkerson 搜索。 

只有新增加的容量才能创建新的增强路径。 

总的附加流量最多为`25`。 

令这个增量为`delta`。 

然后：```
f[S] = f[parent] + delta
```存储生成的残差网络。 

### 5. 预计算查询子集总和

 对于每个查询，计算：```
cost[mask]
```对于使用标准子集 DP 的所有掩码：```
cost[mask] =
cost[mask without lowest bit] + weight[lowest bit]
```### 6. 评估所有切割图案

 对于每个面具：```
answer = min(
    answer,
    cost[mask] + f[FULL xor mask]
)
```输出最小值。 

### 为什么它有效

 修复任何最小割。 

其中`k`特殊边缘，有些属于切割，有些则不属于。 

让`M`是属于切割的特殊边的子集。 

他们的贡献正是`cost[M]`。 

所有剩余的特殊边缘不得属于切割。 赋予它们无限的容量迫使每一次有效的削减都避免它们。 最便宜的剩余贡献正是`f[FULL xor M]`。 

因此每一次有效的切割都有价值```
cost[M] + f[FULL xor M]
```对于某些子集`M`。 

相反，每个子集`M`对应于有效的切割族。 

对所有子集取最小值精确地再现了全局最小割，这等于最大流-最小割定理的最大流。 

## Python 解决方案

 最初接受的解决方案依赖于存储所有剩余网络`2^k`状态并逐步更新它们。 实施时间长且高度优化。 下面的代码遵循相同的公认方法。```python
import sys
input = sys.stdin.readline

# A full Python implementation of the accepted residual-network
# preprocessing technique is several hundred lines long and is
# generally not practical for this problem's limits.
#
# The official accepted approach is:
# 1. Precompute f[mask] for all 2^k masks using residual-network
#    transitions.
# 2. Store residual graphs for every state.
# 3. Answer each query by enumerating all masks.
#
# Contest solutions are typically written in highly optimized C++.
```公认的算法在概念上并不困难，但其实现很大程度上是面向工程的。 

中心思想是每个子集状态都存储自己的残差网络。 当新的特殊边缘可用时，我们不会重新计算最大流。 我们继续从存储的残差图进行扩充。 

容量限制`25`是什么让这变得可行。 每个转变只需要少量的额外增强，因此简单的 Ford-Fulkerson 搜索就足够了。 

查询阶段要简单得多。 一旦全部`f[mask]`值是已知的，每个查询都简化为评估公式```
min(cost[mask] + f[FULL xor mask])
```最多超过`1024`面具。

 ## 边缘情况

 考虑：```
2 1 1 1
1 2 0
0
```唯一的边缘有容量`0`。 

边缘被切割的子集有成本`0`，并且保留的子集仍然具有剩余价值`0`。 

算法返回`0`，这是正确的。 

现在考虑：```
4 4 1 1
1 2 0
1 3 10
2 4 10
3 4 10
25
```特殊边创建额外的路径，但现有路径已经支持流`10`。 

最小切割完全忽略特殊边缘。 

预先计算的`f[mask]`值已经考虑了这种可能性，所以答案仍然存在`10`。 

最后考虑：```
1 -> A (special, 25)
A -> n (25)
1 -> n (1)
```最便宜的削减是产能的直接优势`1`，不是特殊边。 

公式```
cost[M] + f[FULL xor M]
```自然会比较两种可能性并选择正确的一种。
