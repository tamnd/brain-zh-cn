 ## 解决方案
 ## 问题理解

 我们得到了四个单独的袋子，每个袋子里装有一定数量的糖果。 每个包都是不可分割的，必须完全送给两个朋友中的一个。 任务是确定我们是否可以将四个袋子分别分配给任何一个朋友，以便两个朋友最终得到的糖果总数完全相同。 

换句话说，我们将四个整数的多重集划分为两组，并且我们希望两组的总和相等。 

限制非常小：每个值最多为 100，并且只有四个包。 这立即排除了对效率的任何担忧。 任何甚至尝试所有分配或子集的解决方案都足够快，因为可能性的总数固定为$2^4 = 16$。 

因为只有四个项目，所以主要的微妙之处不是性能，而是一致处理所有分区的正确性。 

一个常见的错误是假设贪婪配对有效，例如将最小与最大匹配或仅检查少数组合。 但这会失败，因为结构没有排序，并且最佳分区可能会以不明显的方式混合极端情况。 

例如，考虑：```
1 2 3 4
```贪婪的尝试可能会将 (1,4) 和 (2,3) 配对，这会起作用，但如果启发式方法将 (1,2) 和 (3,4) 配对，则即使存在有效分区，它也会失败。 这表明除非考虑所有分区，否则关于对的部分推理是不可靠的。 

当总和为奇数时，会出现另一种失败情况。 例如：```
1 1 1 2
```总计为 5，因此无论分配如何均等分配都是不可能的。 任何正确的解决方案都必须隐含地拒绝这种情况。 

## 方法

 蛮力的想法是尝试一切可能的方法将四个袋子中的每一个分配给任一朋友。 由于每个包有两个选择，这导致$2^4 = 16$作业。 对于每个作业，我们计算朋友 A 和朋友 B 的糖果总和，并检查它们是否匹配。 

对于如此小的输入大小来说，这已经是最佳选择。 正确性来自于详尽性：每个有效分区恰好对应于四个包的一个二进制分配。 

简化推理的唯一观察结果是，如果我们按照子集进行思考，那么实际上不需要显式地枚举分配：为第一个朋友选择袋子的子集会自动确定第二个朋友。 

一个稍微更具概念性的捷径是观察总和必须是偶数，并且我们正在寻找总和为总数一半的袋子的子集。 对于四个元素，子集枚举很简单。

 ## 算法演练

 1. 计算四个袋子值的总和。 如果总和是奇数，则立即得出结论：不可能进行等分，因为两个相等的整数之和必须为偶数。 
2. 将目标总和定义为总数的一半。 这是每个朋友必须收到的金额。 
3. 迭代四个包的所有子集。 使用 0 到 15 的位掩码表示每个子集，其中每个位指示是否将包分配给第一个好友。 
4. 对于每个子集，计算所选包的总和。 这代表给第一个朋友的糖果。 
5. 如果这个子集总和等于目标，我们就隐式地将剩余的包分配给第二个朋友，并且两个总和匹配。 立即返回 YES。 
6. 如果没有子集达到目标总和，则返回 NO。 

### 为什么它有效

 每个有效的分配都与分配给第一个朋友的行李子集完全对应。 其余的包形成补集子集。 由于我们测试所有子集，因此我们必须测试每个可能的分区。 正确性归结为这样一个事实：总数相等相当于找到总和等于总数一半的子集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a = list(map(int, input().split()))
    total = sum(a)
    
    if total % 2 != 0:
        print("NO")
        return
    
    target = total // 2
    
    # try all subsets of 4 elements
    for mask in range(1 << 4):
        s = 0
        for i in range(4):
            if mask & (1 << i):
                s += a[i]
        if s == target:
            print("YES")
            return
    
    print("NO")

if __name__ == "__main__":
    solve()
```该代码首先读取四个值并计算它们的总数。 当不可能相等时，奇偶校验可以防止不必要的子集枚举。 

位掩码循环枚举所有可能的包分配给第一个朋友。 内循环累加子集和。 一旦找到有效的子集，函数就会提前退出，因为存在就足够了。 

一个微妙的实现细节是我们不需要显式计算第二个朋友的总和。 一旦第一个和与总数的一半匹配，补数也会自动匹配。

 在掩码 0101 处，我们达到目标和 12，所以答案是“是”。 

这证实了存在有效的分区，其中所选子集及其补集的总和均为 12。 

### 示例 2

 输入：```

```总数是 5，这是奇数。 

| 步骤| 总计 | 奇偶校验| 决定|
 | ---| ---| ---| ---|
 | 1 | 5 | 奇数| 否 |

 由于总数无法平均分割，因此我们立即得出结论，不存在有效的分区而不枚举子集。 

这表明奇偶校验正确地修剪了不可能的情况。

 ## 边缘情况

 奇偶校验边缘情况是从一开始就处理的。 对于这样的输入：```
1 1 1 2
```该算法计算总数为 5 并立即返回 NO。 这可以防止不必要的子集枚举。 

对于对称输入，例如：```
2 2 2 2
```该算法仍将通过子集进行工作，但它可以快速找到多个有效掩码，例如选择任意两个总和为 4 的包。 

对于单个有效分割隐藏在许多无效分割中的情况，例如：```
100 1 1 98
```子集搜索确保即使是非直观的组合也能得到测试，并且选择 {100, 1} 的掩码足以达到 101，与目标 101 匹配。
