 ## 解决方案
 ## 问题理解

 我们得到一个非常大的十进制字符串，代表一个数字，恰好`n`数字。 我们最多被允许改变`k`这些数字中，一次一个位置，用其中的任何其他数字替换一个数字`0`到`9`。 执行完后达到`k`进行此类修改时，我们必须获得尽可能小的数量，同时仍然保持表示形式作为有效的`n`-digit 数字，表示第一位数字不能成为`0`除非`n = 1`。 

该任务纯粹是在有限数量的编辑下进行数字操作。 每次编辑都有相同的成本，因此唯一的问题是优先考虑哪些位置，以最大限度地减少最终的词典价值。 

约束条件非常大，`n`最多200,000。 这立即排除了任何考虑所有更改子集或针对每个位置执行嵌套扫描的方法。 任何二次策略，例如尝试所有方法来分配更改或在每次修改后重新计算最佳结果都会太慢，因为`O(n^2)`在最坏的情况下将是 4e10 次操作。 

这个问题的关键微妙之处在于贪婪和有限数量的变化之间的相互作用。 尝试“局部改进数字”而不考虑全局优先级的幼稚方法可能会失败。 例如，即使局部改进看起来有益，但在后面的数字而不是前面的数字上进行支出更改可能会使领先部分不理想。 

当人们试图贪婪地减少任何不为零的数字而不优先考虑较早的位置时，就会出现一种常见的失败情况：

 输入：```
3 1
909
```粗心的策略可能会将最后一位数字更改为`0`生产`909 -> 900`，这在这里是最佳的，但是如果我们有更多的结构，比如`901`和`k=1`，改变最后一位数字给出`900`，同时改变第一位数字给出`001`由于前导零，这是无效的。 如果不仔细处理第一个数字约束，天真的贪婪方法很容易违反正确性。 

当出现另一种边缘情况时`k`足够大以将许多数字归零，但最佳解决方案仍然必须尊重较早的数字在字典顺序上占主导地位。 

这些观察结果表明，我们必须从左到右处理位置，并在最重要的地方使用变化。 

## 方法

 一个蛮力的想法是尝试大小不超过的所有头寸子集`k`并以所有可能的方式替换这些数字。 即使我们简化并假设我们总是用最佳数字替换所选数字，子集的数量本身就是：$$\sum_{i=0}^{k} \binom{n}{i}$$这是指数级的`n`。 和`n = 200000`，这是完全不可行的。 

问题的结构表明了更强的贪婪方向。 最终数字按字典顺序从左到右进行比较，因此前面的数字支配所有后面的数字。 这意味着提高位置上的数字`i`总是比提高位置上的任何数字更有价值`j > i`，前提是这两项改进的操作次数相同。 

由此，正确的策略就出现了：从左到右扫描，只要我们能负担得起，就强制当前数字为`0`（尽可能小的数字），除非我们必须确保第一位数字不为零，除非`n = 1`。 每次我们决定改变一个数字时，我们都会递减`k`。 我们从不重新审视之前的决定，因为一旦数字设置为最佳，再次更改它只会浪费操作。 

这是有效的，因为在最早的位置将数字设置为尽可能小的值会产生每次操作的最大字典顺序减少。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最优贪心 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们从左到右处理数字并维护剩余的变化量。 

1. 将数字作为字符列表读取，以便可以就地修改各个数字。 这避免了重复的字符串连接成本。 
2. 迭代每个索引`i`从`0`到`n - 1`。 在每个位置，我们决定是否应该花一个零钱。 
3.如果`k > 0`，我们考虑是否可以改进这个数字。 最好的改进就是做到这一点`0`。 这始终是最小化数量的最佳选择，因为`0`是最小的数字。 
4. 对于第一个数字（`i = 0`），我们不能将其设置为`0`如果`n > 1`，因为这会引入前导零并使数字无效。 所以我们只有在以下情况下才改变它：`n == 1`。 
5. 对于所有其他职位（`i > 0`)，如果该数字还没有`0`我们还有剩余的更改，我们将其设置为`0`并减少`k`。 
6. 继续，直到我们完成所有数字或耗尽`k`。 

### 为什么它有效

 不变的是，在每一步中，到目前为止构造的数字的前缀是使用已经花费的操作数可实现的最小前缀。 由于字典顺序仅取决于第一个不同的位置，因此尽早最小化每个位置可以保证全局最优性。 任何后续使用剩余操作都无法改善较早的数字，因此，一旦出现有益的减少，保留后续位置的操作永远不会超过使用它们。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
s = list(input().strip())

for i in range(n):
    if k == 0:
        break

    if i == 0:
        if n > 1 and s[i] != '1':
            # we cannot set to 0, best is 1
            if s[i] != '1':
                s[i] = '1'
                k -= 1
    else:
        if s[i] != '0':
            s[i] = '0'
            k -= 1

print("".join(s))
```该解决方案的工作原理是贪婪地在每个位置强制执行尽可能小的数字。 第一个数字被单独处理，因为除非数字的长度为一，否则它不能为零。 对于所有其他数字，如果继续进行操作，任何非零数字都会立即减为零。 

一个微妙的点是我们从不尝试部分改进，例如减少一个数字`7`到`6`。 这是不必要的，因为花费一次操作来完成它`0`按照字典顺序至少总是一样好，因为一旦前缀固定，任何非零数字相对于未来位置的效果都是等效的。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    s = list(input().strip())

    for i in range(n):
        if k == 0:
            break

        if i == 0:
            if n > 1 and s[i] != '1':
                s[i] = '1'
                k -= 1
        else:
            if s[i] != '0':
                s[i] = '0'
                k -= 1

    return "".join(s)

# provided sample
assert run("5 3\n51528\n") == "10028", "sample 1"

# minimum size
assert run("1 0\n7\n") == "7", "single digit no change"

# maximum reduction
assert run("3 3\n999\n") == "100", "force minimal prefix"

# no operations
assert run("4 2\n1234\n") == "1034", "only two zeros possible"

# already optimal
assert run("4 2\n1000\n") == "1000", "no improvement"

# edge leading digit
assert run("2 1\n10\n") == "10", "cannot reduce leading digit to 0"

 ## 边缘情况

 关键的边缘情况是第一个数字大于`1`和`k > 0`。 该算法迫使它`1`， 不是`0`，保持有效性。 例如：

 输入：```
3 2
902
```第一个数字`9`变成`1`，离开`k = 1`。 然后贪婪地最小化剩余的数字。 该算法确保数字保持有效，同时仍然优先考虑字典顺序最小的前缀。 

另一种情况是当所有数字都已经是`0`除了第一个。 在已经最优的位置上不会浪费任何操作，因为条件`s[i] != '0'`防止不必要的减少`k`。 

最终的行为一致地保留了每个使用的操作都会产生最早的字典顺序改进的不变性。
