 ## 解决方案
 # 问题理解

 我们有一个二进制的瓷砖字符串。 瓷砖排成一条线，固定距离控制操作`k`。 站在一块瓷砖前`p`，我们可以翻转瓷砖`p`与瓷砖一起`p + k`，只要第二个图块存在。 在每次翻转之前，我们可以移动线上的任何位置，并将移动的距离作为能量支付。 翻转本身需要花费`m`活力。 

目标不是达成特定的安排。 我们只需要选择一系列的移动和翻转，让绳子留下尽可能多的`1`花最多的钱，尽可能的瓷砖`E`活力。 

操作图是关键结构。 索引具有相同模余数的图块`k`形成一条链：```
r -> r+k -> r+2k -> ...
```翻转总是影响这些链之一中的两个相邻顶点。 

约束是围绕这一观察而设计的。 字符串长度最多为`500`，并且测试用例的所有长度之和最多为`1000`，因此立方时间附近的解是可以接受的。 额外保证`floor(n/k) <= 50`意味着每条链最多有`51`瓷砖。 这可以防止链内的指数处理，并允许对翻转次数进行动态编程。 

能量极限可以大到`10^18`，所以我们不能用能量作为 DP 维度。 重要的成本是翻转的次数，因为每次翻转的价格都是相同的。 相反，必须从结构上处理运动。 

一些边缘情况很容易被忽略。 

如果无法负担得起翻转，那么答案很简单：现有的数量`1`瓷砖。 例如：```
n = 3, k = 1, E = 0, m = 5
s = 101
```输出是`2`。 总是尝试至少一项操作的解决方案会错误地减少答案。 

如果`m = 0`，翻转是自由的，只有运动消耗能量。 例如：```
n = 4, k = 1, E = 2, m = 0
s = 0000
```我们可以移动到位置`2`并自由使用前两条边，产生`1110`，所以答案是`3`。 治疗`E / m`如果不处理零就会失败。 

如果一条链的块数为奇数，则无法更改其奇偶性。 例如：```
n = 3, k = 1, E = 100, m = 1
s = 000
```输出是`2`， 不是`3`。 整个链奇偶校验是不变的，因为每个操作恰好翻转两个块。 

# 方法

 直接的暴力方法会尝试每一种可能的翻转。 最多有`n-k`可能的翻转位置，因此在最坏的情况下有数百种二元选择。 枚举它们需要大约`2^(n-k)`可能性，这远远超出了即使是很小的限制所允许的。 

蛮力之所以诱人，是因为每次选择的翻转都有一个简单的效果：它改变了两位。 困难在于选择之间的相互作用。 选择一条边会改变同一链中相邻边的有用效果，因此独立的贪婪决策不起作用。 

第一个重要的减少来自运动。 假设我们选择一组翻转位置。 设最大的选择位置为`x`。 从位置开始`0`，径直走到`x`访问途中的每个较小位置，因此我们可以执行每个选定的翻转，而无需额外的移动。 移动成本正好是`x`。 之后就没有再回来的理由了。 

这改变了问题。 我们可以尝试每一个可能的最远的翻转位置`x`。 付款后`x`运动能量，我们只需要在位置之间使用有限次数的翻转来最大化运动能量`x`。 

第二个观察结果是翻转仅连接由`k`，所以每个模`k`链是独立的。 对于固定的翻转限制，我们分别求解每个链，并将它们的答案与所使用的翻转次数的背包 DP 结合起来。 

蛮力之所以有效，是因为每个操作序列都可以通过其选择的边来描述，但会失败，因为选择的数量是指数级的。 链分解和运动观察将问题简化为路径上的小型动态程序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最佳| O(n^3) | O(n^3) | O(n^2) | O(n^2) | 已接受 |

 # 算法演练

 1. 数一下初始的个数。 这始终是一个可能的答案，因为什么都不做是不允许的。 
2. 考虑每一个可能的最大翻转位置`x`。 如果`x`能源已经太贵了，跳过它。 价值`x`代表我们需要访问的最远点。 
3. 计算支付移动费用后可以进行多少次翻转。 如果`m`是正数，这就是`(E - x) // m`。 如果`m`为零，则可以使用所有可用的翻转。 
4. 根据具有相同余数模的索引将字符串分割成链`k`。 对于每个链，计算在使用该链中的一定数量的可用翻转后可获得的最佳数量。 
5. 用背包DP合并所有链。 DP 指数是花费的翻转次数。 对于每个链结果，尝试将其可能的翻转计数添加到全局状态。 
6.对于当前`x`，检查能量预算允许的每次翻转计数并更新答案。 

这样做的原因是翻转永远不会在两个不同的模之间交叉`k`链。 一旦分配给每个链的翻转次数固定，链就不会互相影响。 唯一共享的资源是翻转的总数，这正是背包所结合的。 

为什么它有效：

 对于任何选定的一组操作，令`x`是翻转开始的最大位置。 每个选择的起始位置最多为`x`，所以步行从`0`到`x`允许所有翻转准确地执行`x`移动成本。 剩余预算仅限制翻转次数。 

在一条链内，路径 DP 会考虑其可用边的每个可能选择。 结合所有链的最优结果涵盖了所有可能的全局边选择。 由于每个有效操作序列都对应于算法所考虑的状态之一，因此最大产生值是最优的。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def build_chain_dp(bits, available_edges, limit):
    n = len(bits)
    dp = [[-10**9] * 2 for _ in range(limit + 1)]
    dp[0][0] = 0

    for i in range(n):
        ndp = [[-10**9] * 2 for _ in range(limit + 1)]
        if i < available_edges:
            choices = (0, 1)
        else:
            choices = (0,)

        for used in range(limit + 1):
            for prev in range(2):
                cur = dp[used][prev]
                if cur < 0:
                    continue
                for take in choices:
                    if used + take <= limit:
                        value = bits[i] ^ prev ^ take
                        ndp[used + take][take] = max(
                            ndp[used + take][take],
                            cur + value
                        )
        dp = ndp

    ans = [0] * (limit + 1)
    for used in range(limit + 1):
        ans[used] = max(dp[used][0], dp[used][1])
    return ans

def solve_case(n, k, E, m, s):
    bits = [int(c) for c in s]
    answer = sum(bits)

    chains = []
    for r in range(k):
        chain = []
        pos = r
        while pos < n:
            chain.append(bits[pos])
            pos += k
        if chain:
            chains.append((r, chain))

    cache = {}

    max_start = n - k - 1
    for x in range(max_start + 1):
        if x > E:
            continue

        if m == 0:
            flips = n
        else:
            flips = min(n, (E - x) // m)

        if flips < 0:
            continue

        global_dp = [-10**9] * (flips + 1)
        global_dp[0] = 0

        for r, chain in chains:
            if r <= x:
                edges = min(len(chain) - 1, (x - r) // k + 1)
            else:
                edges = 0

            key = (r, edges, flips)
            if key not in cache:
                cache[key] = build_chain_dp(chain, edges, flips)

            values = cache[key]

            ndp = [-10**9] * (flips + 1)
            for a in range(flips + 1):
                if global_dp[a] < 0:
                    continue
                for b in range(flips - a + 1):
                    if values[b] >= 0:
                        ndp[a + b] = max(ndp[a + b], global_dp[a] + values[b])
            global_dp = ndp

        answer = max(answer, max(global_dp))

    return answer

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, k, E, m = map(int, input().split())
        s = input().strip()
        out.append(str(solve_case(n, k, E, m, s)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该解决方案首先将字符串分成模数`k`链。 每个链都由一个小的 DP 来解决，其中状态会记住有多少条边被翻转以及前一条边是否被翻转。 前一个边标志就足够了，因为顶点仅依赖于两个相邻边。 

外循环尝试所有可能的最远翻转位置。 变量`flips`是支付移动成本后可承受的最大操作次数。 特殊情况`m == 0`避免被零除并正确地允许每个可到达的翻转。 

背包合并结合了连锁答案。 的索引为`global_dp`是迄今为止使用的翻转总数。 所有有效翻转计数的最大值给出了所选最远位置的最佳结果。

 # 边缘情况

 对于零能量情况：```
3 1 0 5
101
```不会发生任何移动或翻转，因为每次翻转都需要能量。 该算法从初始计数开始，即`2`，并且永远不会改进它。 

免费翻转：```
4 1 2 0
0000
```该算法将支付移动后的翻转次数视为无限次。 最远的负担得起的位置是`2`，允许使用两条边。 链 DP 找到最佳可达配置，给出`3`那些。 

对于奇偶校验保留：```
3 1 100 1
000
```链条是`0 -> 1 -> 2`。 翻转任一边缘都会改变两个图块，因此图块数量的奇偶性保持偶数。 DP 考虑两条边，但无法达到三个边，返回`2`。 

对于没有可用翻转的链条：```
5 4 10 1
00000
```只有一个可能的边。 该算法创建一条短链和几条单块链。 单个图块贡献其原始值，因为没有任何操作可以影响它们，这避免了意外地在有效范围之外应用翻转。
