 ## 解决方案
 ## 问题理解

 该问题中的每个数字都不是以其扩展形式给出的，而是作为紧凑的描述给出的。 我们没有写出完整的整数，而是给出了一个基值`x`和一些尾随零`p`，这意味着实际数量是`x × 10^p`。 

因此，每个测试用例都会给出两个这样的“十进制移位”数字。 任务只是确定两个结果整数中哪一个更大，或者它们是否相等。 

关键的难点在于`p`可以大到 10^6。 这使得构建实际的数字变得不可能，因为写下 10^6 位数字已经远远超出了内存和时间的限制。 比较必须纯粹从数字的结构来进行。 

约束允许最多 10^4 个测试用例。 由于时间和内存爆炸，任何尝试显式构建或模拟完整数字的解决方案都会立即失败。 即使基于字符串的构造也是不可行的，因为单个测试用例可能需要多达一百万位数字。 

当基数很小但指数不同时，就会出现微妙的边缘情况。 例如，比较`1 × 10^5`和`10 × 10^4`看起来像比较`100000`和`100000`，即使基值不同，它们也是相等的。 一种幼稚的比较方法`(x, p)`按字典顺序会错误地得出结论`10 × 10^4`更大，因为`10 > 1`。 

例如，当一个数字的指数完全支配另一个数字的大小时，就会出现另一种失败情况`999 × 10^0`相对`1 × 10^3`。 正确答案完全取决于扩展后的数字长度，而不是基数。 

因此，比较必须模拟算术幅度而不构造数字。 

## 方法

 直接暴力方法将通过附加来构造每个数字的完整整数表示`p`零到十进制字符串`x`，然后对结果字符串进行数值比较。 这在概念上是简单且正确的，因为它反映了实际数字。 

然而，在最坏的情况下，每个数字最多可以有 10^6 位。 对于多达 10^4 个测试用例，这会导致理论输出大小约为 10^10 个字符。 即使忽略内存限制，简单地写入或比较这些字符串也将远远超出时间限制。 

关键的观察结果是尾随零仅影响数字的小数位数，而不影响其内部数字结构。 唯一有意义的比较来自扩展后的总数字长度。 如果两个数字的有效长度不同，则较长的数字立即较大。 如果它们具有相同的长度，则比较会减少为逐位比较它们的有效前缀，因为尾随零完美对齐。 

这将问题简化为平衡数字长度，然后比较相等长度数字的标准化表示。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（构建完整数字）| O(10^p 位数字之和) | O(10^p 之和) | 太慢了 |
 | 最优（长度+归一化）| O(t · log x) | O(t · log x) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将每个数字视为有两个组成部分：重要部分`x`和幅度变化`p`。 

1. 计算每个数字的有效长度为`len(str(x)) + p`。 

这表示在不构造完整扩展数字的情况下，该数字将具有多少位数字。 
2. 如果两个长度不同，则长度较大的数字自动较大。 

这直接源于这样一个事实：添加更多的尾随零总是会使幅度增加十个数量级。 
3. 如果长度相等，我们不能仅根据长度来决定。 在这种情况下，我们逐位比较，就好像两个数字都完全展开一样。 
4. 为了在不扩展的情况下进行比较，我们在概念上对齐两个数字：

 较大的指数为较小的基数提供了额外的尾随零，因此我们可以有效地进行比较`x1 × 10^(p1 - p2)`和`x2 × 10^(p2 - p1)`取决于哪个指数更大。 
5. 我们通过在逻辑上用零填充较小的表示并仅比较重叠的重要部分来模拟这一点。 
6.比较是作为构造的对齐表示的字符串比较来执行的，但没有实际具体化完整的字符串。 

### 为什么它有效

 每个数字都具有以下形式`x × 10^p`，这相当于移动小数表示`x`向左`p`职位。 以 10 为基数的数字的大小首先由数字计数确定，然后只有当长度匹配时才通过数字的字典顺序比较确定。 

通过将每个数字分为“长度类别”和“对齐的数字序列”，我们保留了实整数的精确顺序。 任何变换都不会改变相对顺序，因为乘以 10 的幂只影响数字位置，而不影响数字值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
out = []

for _ in range(t):
    x1, p1 = map(int, input().split())
    x2, p2 = map(int, input().split())

    s1 = str(x1)
    s2 = str(x2)

    len1 = len(s1) + p1
    len2 = len(s2) + p2

    if len1 > len2:
        out.append(">")
        continue
    if len1 < len2:
        out.append("<")
        continue

    # same length case: compare digit by digit
    i = 0
    j = 0
    zero1 = p1
    zero2 = p2

    while i < len(s1) or j < len(s2):
        d1 = int(s1[i]) if i < len(s1) else 0
        d2 = int(s2[j]) if j < len(s2) else 0

        if d1 != d2:
            out.append(">" if d1 > d2 else "<")
            break

        i += 1
        j += 1
    else:
        out.append("=")

sys.stdout.write("\n".join(out))
```实现首先将每个基数转换为字符串，以便数字访问高效。 它首先比较总有效长度，这可以立即解决大多数情况。 

当长度匹配时，代码执行同步数字比较。 一旦一个字符串用完数字，它就会隐式地将缺失的位置视为零，这与原始数字中尾随零的效果完全一致。 

一个微妙的点是我们从不显式构造填充字符串。 相反，我们通过在比较期间将超出范围的位置视为零来模拟填充。 这可以避免内存溢出的风险，同时保持正确性。 

## 工作示例

 考虑样本对`(2, 1)`和`(19, 0)`。 

我们比较有效长度：`2 × 10^1`长度为 2，而`19 × 10^0`长度也为 2。由于长度相等，我们逐位比较。 

| 步骤| s1 数字 | s2 数字 | 决定|
 | ---| ---| ---| ---|
 | 1 | 2 | 1 | 2 > 1 → 第一个更大 |

 所以输出是`>`。 

现在考虑`(10, 2)`和`(100, 1)`。 

有效长度：均为3位。 

| 步骤| s1 数字 | s2 数字 | 决定|
 | ---| ---| ---| ---|
 | 1 | 1 | 1 | 等于|
 | 2 | 0 | 0 | 等于|
 | 3 | 0 | 0 | 等于|

 所有数字都匹配，所以结果是`=`。 

这些示例表明，该算法首先使用结构优势（长度），并且仅在必要时才回退到数字对齐。

 ## 边缘情况

 一种边缘情况是当一个数字由于尾随零而变得明显更长时，即使它的基数很小。 用于输入`1 5`和`999 0`，第一个数字变为 100000，而第二个数字仍为 999。算法立即比较长度，发现第一个数字更长，然后输出`>`无需检查数字。 

当两个数字最终具有相同的有效长度但需要数字对齐时，会出现另一种边缘情况。 为了`10 2`和`100 1`，都扩展到三位数。 算法逐位比较，发现每个位置都相等，正确输出`=`。 

第三种情况涉及具有不同指数的相同基值，例如`10 1`和`10 2`。 有效长度不同，因此无需进行数字检查即可立即解析比较，正确反映添加尾随零会增加幅度。
