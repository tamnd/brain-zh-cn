 ## 解决方案
 ## 问题理解

 我们需要从每种配件中精确选择一个配件来构建一台计算机。 每个配件都有价格和使用寿命。 一旦第一个选定的配件达到其使用寿命，计算机就会停止工作，因此整机的寿命是所有选定配件中最短的使用寿命。 

目标是最小化单位时间的价格，即：$$\frac{\text{sum of selected prices}}{\text{minimum selected service life}}$$如果多种选择的最低比例相同，则应选择总价最小的一种。 

输入给出配件种类的数量以及每种配件的可用配件的数量。 对于每种配件，以下值描述了每个配件：其使用寿命和价格。 输出是所有最优选择中总价格最小的。 

限制是$N,M \le 1000$。 配件多达一百万个，因此不可能检查每种可能的组合。 即使尝试每种类型中的所有选择也会呈指数级增长，因为可能的计算机数量是$M^N$。 使用寿命值限制为 1000，这是允许基于迭代可能的生命周期的解决方案的关键限制。 

棘手的情况来自这样一个事实：控制计算机的是最短使用寿命，而不是最长或平均使用寿命。 

例如：```
1 2
5 10 10 1
```有一种、两种配件。 选择第一个配件的比例为$10/5=2$。 选择第二个给出$1/10=0.1$，所以答案是：```
1
```仅搜索最便宜的配件的粗心方法在这里可能有效，但在多种情况下它可能会失败，因为非常便宜且寿命短的配件会缩短整个计算机的使用寿命。 

另一个边缘情况是平局：```
2 2
2 5 5 10
2 5 5 10
```选择两个便宜的配件给出价格$10$， 寿命$2$， 比率$5$。 选择两个昂贵的配件就给出了价格$20$， 寿命$5$， 比率$4$。 尽管价格较高，但第二种选择获胜。 仅比较总价会得出错误的结果。 

## 方法

 直接的强力解决方案将尝试所有可能的配件选择。 对于每种计算机配置，我们计算总价格和最短使用寿命，然后比较所得比率。 这是正确的，因为它检查了每一个可能的答案。 然而，随着$N$种类和$M$每种选择，配置数量为$M^N$。 即使是为了$N=1000$，这远远超出了可以处理的范围。 

有用的观察来自于观察分母。 计算机的使用寿命必须等于所选配件的使用寿命之一。 由于使用寿命最多为 1000，因此只有 1000 个可能的寿命值。 

假设我们想要一台寿命至少为$L$。 每个所选配件必须至少有使用寿命$L$。 对于每种类型，我们应该选择满足此要求的最便宜的配件。 这些最便宜价格的总和是至少存活下来的任何计算机的最低可能价格$L$时间单位。 

如果我们计算每个可能的值$L$，则该寿命的比率为：$$\frac{\text{minimum price with all service lives }\ge L}{L}$$这些比率中最小的一个就是答案。 这样做的原因是最佳计算机有一定的实际寿命$T$。 当我们评估时$L=T$，该算法准确地考虑了所有能够至少达到该寿命的计算机，并包括最佳计算机。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(M^N)$|$O(1)$| 太慢了|
 | 最佳|$O(N \times M + N \times S)$|$O(S)$| 已接受 |

 这里$S=1000$，最大可能的使用寿命。 

## 算法演练

 1. 阅读所有配件，并针对每个使用寿命值，存储具有该使用寿命的每种配件的最便宜价格。 我们需要这些信息，因为稍后我们将为每个可能的生命周期阈值构建答案。 
2. 使用寿命从1000年降至1年，同时保持所有配件中每种产品最便宜的可用价格，使用寿命至少为当前值。 向下移动允许我们在配件的使用寿命可用时添加配件，而不是重复搜索整个列表。 
3. 对于每个生命周期值，检查每种类型是否至少有一个可用配件。 如果是这样，当前存储的价格就构成了至少能存活这么长时间的最便宜的计算机。 
4. 将总价格与当前生命周期之间的比率与迄今为止找到的最佳比率进行比较。 分数与乘法而不是浮点运算进行比较，以避免精度问题。 
5. 如果两个选择的比率完全相同，则保留较小的总价格，因为该问题要求最优比率中的最小价格。 

为什么它有效：

 对于任何选定的计算机来说，其使用寿命是其配件中最短的使用寿命。 就让那一生$L$。 该算法考虑这个精确值。 在所有能够生存的计算机中$L$单位时间，它会选择尽可能便宜的一个，因此它的比率不比原始计算机的比率差。 由于检查了每个可能的寿命，因此找到的最佳比率必定是全局最优的。 领带处理在具有相同最佳比率的所有配置中保持最低的价格。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())

    exact = [[10**18] * N for _ in range(1001)]

    for i in range(N):
        data = list(map(int, input().split()))
        for j in range(0, 2 * M, 2):
            s = data[j]
            p = data[j + 1]
            if p < exact[s][i]:
                exact[s][i] = p

    current = [10**18] * N
    best_num = 10**18
    best_den = 1
    answer = 0

    for life in range(1000, 0, -1):
        for kind in range(N):
            if exact[life][kind] < current[kind]:
                current[kind] = exact[life][kind]

        if max(current) == 10**18:
            continue

        total = sum(current)

        if total * best_den < best_num * life:
            best_num = total
            best_den = life
            answer = total
        elif total * best_den == best_num * life:
            if total < answer:
                answer = total

    print(answer)

if __name__ == "__main__":
    solve()
```这`exact`阵列存储每种确切使用寿命的最便宜的配件。 它的尺寸很小，因为使用寿命以 1000 为界限。 

向下循环保持`current`， 在哪里`current[i]`是目前配件种类最便宜的价格`i`使用寿命至少为当前寿命。 这可以避免多次重新计算相同的最小值。 

比较使用交叉乘法：$$\frac{a}{b}<\frac{c}{d}$$被检查为：$$a \times d < c \times b$$这可以避免浮点错误。 Python 整数还可以避免溢出问题。 

更新顺序很重要。 我们在评估之前添加具有当前寿命的所有配件，因为使用寿命恰好等于当前阈值的配件是有效的。

 ## 边缘情况

 当一种类型没有足够长的生命周期的附件时，该生命周期就无法形成一台有效的计算机。 例如：```
2 1
5 10
3 20
```在生命周期 5 时，第二种没有有效的附件，因此算法会跳过它。 在生命周期 3 时，两种类型都可用，总价格为 30，给出唯一有效的答案。 

当最便宜的配件的使用寿命很短时，不应自动选择它。 为了：```
2 2
1 1 10 100
1 1 10 100
```该算法评估生命周期 10 并找到总价格 200，比率为 20，而生命周期 1 给出总价格 2，比率为 2。即使总价格较大，它也会正确选择单位时间更便宜的选项。 

当多个生命周期给出相同的比率时，最终比较必须保留较小的价格。 该算法通过交叉乘法检查相等性，因此它可以处理精确的平局，而不会出现浮点错误。
