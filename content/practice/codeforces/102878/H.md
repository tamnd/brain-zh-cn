 ## 解决方案
 ## 问题理解

 该游戏在有向无环图上进行。 单轮从节点 1 开始，到到达节点 n 时结束。 每次轮流访问一个节点时，该节点都会将其奖励贡献给总分。 每个有向边在所有回合中只能使用有限次数。 目标是选择从 1 到 n 的路径集合，以提供最大可能的收集奖励总和。 

重要的细节是，多个转弯可以在顶点上重叠，但它们不能超过任何边的容量。 这使得该问题不同于寻找最佳单一路径。 局部最佳路径可能会消耗稍后允许许多其他有价值路径的边缘。 

对于图算法来说，约束足够小，但对于尝试所有可能的路径组合来说，约束太大。 最多有 100 个顶点和 500 个边，DAG 中可能的路径总数仍然可以是指数的，因此枚举路径或尝试每个转弯子集是不可能的。 我们需要一个基于图结构的多项式解。 

一些边缘情况可能会破坏不正确的实现。 考虑一张图，其中从 1 到 n 只有一条路径：```
2 1
5 7
1 2 3
```答案是36，因为同一条路径可以玩3次，并且每次玩都会获得两个节点奖励。 只找到一条最佳路径的解决方案将返回 12 并且失败。 

另一个棘手的情况是两条路径共享有限的边缘：```
4 4
1 10 1 1
1 2 1
2 4 1
1 3 5
3 4 1
```答案是 18。通过节点 2 的路径给出 12，通过节点 3 的路径给出 7。始终选择当前最有价值路径的贪婪方法可能会消耗其他示例中的共享瓶颈，并阻止更好的全局分布。 

节点1的奖励也很容易被错过。 玩家从节点 1 开始每个回合，示例显示该起始节点对得分有贡献。 任何流模型必须对每个使用的路径对节点 1 和节点 n 精确计数一次。 

## 方法

 暴力的想法是重复搜索从节点 1 到节点 n 的最有利可图的路径，使用它一次，减少其边的容量，一直持续到没有路径为止。 这适用于一些小情况，因为每个选择的路径都是有效的，并且每个使用的边都遵守规则。 

问题在于，每个时刻选择的最佳路径并不是全局最优的。 更重要的是，DAG 中可能的路径数量可能是指数级的，因此即使存储所有候选路径也是不可能的。 如果有许多不同的分支，搜索空间就会远远超出约束所允许的范围。 

关键的观察是，每一圈都是从节点 1 到节点 n 的一个流量单位。 边缘通过限制正是边缘容量。 总奖励附加到流单元使用的每个顶点，这意味着我们可以通过将每个顶点拆分为传入和传出副本，将顶点奖励转换为边上的成本。 

分割后，通过顶点发送一个单位的流会强制流通过代表该顶点奖励的边。 给予边缘成本`-a[i]`将问题转化为寻找最小成本最大流量。 由于所有奖励都是正的，因此每条额外的可能路径都会增加答案，因此我们不断增加，直到从 1 到 n 的路径不存在。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 路径数量呈指数增长 | 指数| 太慢了|
 | 最佳 | O(F * V * E) 与 SPFA，其中 F 是总流量 | O(V + E) | 已接受 |

 ## 算法演练

 1. 分割每个原始顶点`i`分成两个节点：`i_in`和`i_out`。 添加一条边`i_in`到`i_out`具有无限的容量和成本`-a[i]`。 通过这条边代表收集该顶点的奖励。 
2.更换每条原有道路`u -> v`有一个边缘从`u_out`到`v_in`具有给定的容量和零成本。 通行能力保持不变，因为道路的使用次数仍然有限。 
3. 启动最小成本最大流算法`1_in`到`n_out`。 每条最短的增广路径都代表一个可玩的回合。 负成本使得盈利路径的总成本较低。 
4. 每次增强后，将该流程获得的奖励金额添加到答案中。 继续下去，直到不存在增广路径。 
5. 输出最终最小成本的负数，因为流量成本被存储为负奖励。 

为什么它有效：

 每个有效的游戏策略都是从节点 1 到节点 n 的路径的集合。 每条路径可以用一个流量单位来表示，并且边缘容量保证没有一条道路的使用次数超过允许的次数。 访问该顶点的每个单元都会恰好穿过顶点分割边一次，因此它们的负成本正好减去收集的奖励。 因此，最小化总成本相当于最大化收集的黄金总量。 由于所有奖励都是正的，因此每个可用的增广路径都对应于另一个有利可图的回合，因此算法在没有合法回合剩余时准确停止。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

class Edge:
    __slots__ = ("to", "rev", "cap", "cost")

    def __init__(self, to, rev, cap, cost):
        self.to = to
        self.rev = rev
        self.cap = cap
        self.cost = cost

def add_edge(g, u, v, cap, cost):
    g[u].append(Edge(v, len(g[v]), cap, cost))
    g[v].append(Edge(u, len(g[u]) - 1, 0, -cost))

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    size = 2 * n
    graph = [[] for _ in range(size)]

    def inn(x):
        return 2 * x

    def out(x):
        return 2 * x + 1

    INF = 10**9

    for i in range(n):
        add_edge(graph, inn(i), out(i), INF, -a[i])

    for _ in range(m):
        u, v, c = map(int, input().split())
        u -= 1
        v -= 1
        add_edge(graph, out(u), inn(v), c, 0)

    source = inn(0)
    sink = out(n - 1)

    ans = 0

    while True:
        dist = [10**18] * size
        inq = [False] * size
        parent = [(-1, -1)] * size

        dist[source] = 0
        q = deque([source])
        inq[source] = True

        while q:
            u = q.popleft()
            inq[u] = False
            for idx, e in enumerate(graph[u]):
                if e.cap and dist[e.to] > dist[u] + e.cost:
                    dist[e.to] = dist[u] + e.cost
                    parent[e.to] = (u, idx)
                    if not inq[e.to]:
                        inq[e.to] = True
                        q.append(e.to)

        if dist[sink] == 10**18:
            break

        flow = INF
        cur = sink
        while cur != source:
            u, idx = parent[cur]
            flow = min(flow, graph[u][idx].cap)
            cur = u

        cur = sink
        while cur != source:
            u, idx = parent[cur]
            e = graph[u][idx]
            e.cap -= flow
            graph[cur][e.rev].cap += flow
            cur = u

        ans -= dist[sink] * flow

    print(ans)

if __name__ == "__main__":
    solve()
```实现直接遵循流程模型。 这`add_edge`函数创建前向边缘及其剩余边缘，这允许稍后的增强路径撤消先前的选择（如果这改进了最终答案）。 

该图每个原始顶点使用两个索引。 从传入副本到传出副本的边存储奖励，而原始道路将传出副本连接到传入副本。 源是节点1的传入副本，因为必须收集起始节点奖励。 接收器是节点 n 的传出副本，因为到达节点 n 意味着在收集其奖励后该轮次完成。 

SPFA 循环在残差图中找到最便宜的增广路径。 负边成本在这里是安全的，因为该图表示具有剩余边的流网络，并且算法自然地处理它们。 容量是整数，因此每次增强都会发送整数圈。

 ## 边缘情况

 对于重复路径的情况：```
2 1
5 7
1 2 3
```分割图包含节点 1 的奖励边和成本`-5`节点 2 的成本`-7`。 该道路的容量为 3，因此最小成本流算法发送 3 个单元。 最终成本为`-36`，得出正确答案 36。 

对于起始节点奖励情况：```
3 2
10 1 1
1 2 1
2 3 1
```一个常见的错误是只计算离开节点 1 后的节点。流程开始于`1_in`，穿过节点 1 的奖励边，然后继续穿过该路径。 唯一可能的回合收集`10 + 1 + 1 = 12`，这与预期得分相符。 

对于耗尽的瓶颈，残差图很重要。 如果早期的贪婪选择阻止了更好的安排，则流实现创建的反向边允许算法取消先前的选择并重新路由流。 这一特性使全局最优成为可能，而不仅仅是一系列局部最佳路径。
