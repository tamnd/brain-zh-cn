 ## 解决方案
 ## 问题理解

 我们有一圈对象，每个对象都有一个正值。 移动会移除一个仍然存在的对象。 从该删除中获得的分数是已删除对象的当前两个邻居与已删除对象自身值的乘积。 这两个邻居是此时剩余环中紧邻它旁边的对象。 在删除除一个之外的所有对象后，最后一个剩余的对象将被删除并仅贡献其自身的值。 目标是选择使总分最大化的移除顺序。 

输入给出了围绕圆放置的对象的数量和值。 输出是可能的最大总分。 这些值是正数，因此每个选择都会影响未来的乘法，只有通过这些乘法，对象才能保持为邻居。 约束允许最多 500 个对象，这排除了探索所有可能的移除顺序，因为可能的序列数量呈阶乘增长。 需要围绕 O(n³) 的动态编程解决方案，因为大约 1.25 亿次状态转换是适合严格实现的上限。 

主要的困难是圆没有自然的起点或终点。 将第一个对象视为永久边界的粗心解决方案会失去可能的最佳顺序，因为任何对象都可能是最终的幸存者。 

例如，对于一个对象：```
Input:
1
7

Output:
7
```假设在删除之前必须始终有两个邻居的解决方案将失败，因为使用特殊的最终规则删除唯一的对象。 

另一个重要案例是：```
Input:
4
1 2 3 4

Output:
84
```如果我们在错误的地方打破圆圈并只解决一种线性排列，我们可能会错过最佳顺序。 该圆圈允许被选为最终幸存者的对象确定最佳切割。 

第三种情况是重复值：```
Input:
3
5 5 5

Output:
255
```答案是移除一个物体得 125 分，移除第二个物体得 125 分，移除最后一个物体得 5 分。 意外地将相同值视为相同位置的实现可能会错误地减少可用选择。 

## 方法

 直接的方法是模拟每一种可能的移除顺序。 对于每一个第一步，我们都会删除一个对象，更新圆圈，然后递归地尝试每一个可能的下一步。 这是正确的，因为每个有效的游戏都由一个选择序列表示。 然而，对于 n 个对象，第一步有 n 个选择，第二步有 n-1 个选择，依此类推。 订单数量为 n!，即使输入很小，这也是不可能的。 

有用的观察来自于改变问题。 不要决定先删除哪个对象，而是决定在较小的间隔内最后删除哪个对象。 这与区间动态规划问题中使用的思维反转相同。 

如果将两个对象保留为边界，则严格位于它们之间的对象形成独立的子问题。 假设对象 k 是边界 l 和 r 之间最后移除的对象。 此时，k 的邻居恰好是 l 和 r，因此该区间内的最终操作给出的分数为 a[l] × a[k] × a[r]。 k之前移除的所有内容都属于两个较小的区间，可以独立求解。 

唯一剩下的问题是圆圈。 我们复制该数组，将每个可能的圆弧段转换为正常区间。 我们计算长度最多为 n 的段的间隔值。 最终幸存对象的每种可能选择都显示为这些间隔之一。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了|
 | 最佳 | O(n3) | O(n²) | 已接受 |

 ## 算法演练

 1. 复制数组，使圆形排列成为每个位置包含两个副本的线性数组。 现在，任何圆切割都可以用长度为 n 的连续线段表示。 
2. 定义`dp[l][r]`作为通过严格删除位置 l 和 r 之间的所有对象同时保持 l 和 r 作为边界而获得的最大分数。 这个定义之所以有效，是因为区间内的最后一个移除必须在这两个边界之间都有其邻居。 
3. 将边界之间没有对象的间隔初始化为零。 没有任何内容可以删除，因此这些状态不会贡献任何分数。 
4. 通过增加长度来处理间隔。 对于每个间隔`(l, r)`，尝试所有可能的最后删除的对象`k`他们之间。 候选分数是左边部分的最佳分数、右边部分的最佳分数以及最后去掉k个得到的分数。 
5. 计算完所有间隔后，检查双倍数组中长度为 n 的每个段。 每一段对应于在原始圆上选择一个起点。 添加最终幸存对象的值，即用于切割的边界，并取最大值。 

为什么它有效：每个完整的游戏都有一个最终幸存的对象。 如果我们将该对象想象为边界，则所有其他删除都发生在通过切割那里的圆而形成的间隔内。 在任何间隔内，最后删除的对象将剩余操作分成两个独立的间隔，并且递归检查该对象的每个可能的选择。 由于考虑了每个间隔内每个可能的最终幸存者和每个可能的最后移除，因此动态程序包括每个有效的游戏并且从不组合不兼容的选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    if n == 1:
        print(a[0])
        return

    b = a + a
    m = 2 * n

    dp = [[0] * m for _ in range(m)]

    for length in range(2, n + 1):
        for l in range(m - length):
            r = l + length
            best = 0
            for k in range(l + 1, r):
                value = dp[l][k] + dp[k][r] + b[l] * b[k] * b[r]
                if value > best:
                    best = value
            dp[l][r] = best

    ans = 0
    for start in range(n):
        end = start + n
        ans = max(ans, dp[start][end] + b[start])

    print(ans)

if __name__ == "__main__":
    solve()
```重复的数组`b`无需对环绕邻居进行特殊处理。 一段开始于`start`并结束于`start + n`代表整个圆`start`被选为最后的幸存者。 

桌子`dp`仅存储具有两个幸存边界的间隔。 转换会尝试每个可能的最后删除的对象，这就是乘法使用两个端点和中间位置的原因。 

间隔长度循环从小范围开始，因为较大的间隔取决于较小的间隔。 最终的答案是单独添加幸存者的值，因为最后一个对象没有收到正常的三对象相乘分数。 

Python 整数可以安全地处理大值。 最大分数可能会超过 32 位整数限制，因为会累加许多乘法项。

 ## 边缘情况

 对于单个对象，动态规划表是不必要的。 唯一可能的操作是最终移除，因此算法直接返回对象本身的值。 

对于两个对象，没有第三个邻居的选择。 首先删除任一对象会给出两个值与剩余对象的乘积，然后是剩余值。 该实现自然地处理了这一问题，因为区间 DP 包含一个可能的中间对象，并且随后添加最终的幸存者。 

对于重复值，即使它们的数量相等，位置仍然很重要。 双倍数组使每个位置保持独立，因此动态程序会探索所有可能的圆形切割，而不是将相等的对象折叠在一起。 

对于圆形边界情况，通过扫描双倍数组中所有长度为 n 的间隔来测试每个可能的幸存者。 将第一个输入元素固定为幸存者的解决方案只会评估这些可能性中的一个，并且可能会错过最佳值。
