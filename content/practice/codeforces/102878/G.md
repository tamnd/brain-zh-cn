 ## 解决方案
 ## 问题理解

 该游戏是用单堆进行的，其中包含`n`纸球。 龙龙和毛毛的合法招式不同。 龙龙有一组允许他删除的号码，毛毛还有另一组。 在一轮中，玩家从自己的一组中选择一个数字，并精确地移走相应数量的球，但前提是该堆包含足够的球。 无法采取行动的玩家就输了。 任务是确定第一位玩家 Long Long 能否以最佳发挥取得胜利。 

输入给出了球的初始数量、两个移动组的大小以及两个组本身。 输出是所需格式的获胜者姓名。 问题的重要部分是玩家有不同的移动选择，因此普通的公正尼姆理论并不直接适用。 国家取决于轮到谁了。 

对于动态规划来说，约束足够小。 桩数可达 5000，每个移动集最多有 100 个值。 这意味着解决方案`n * m`，大约有 500,000 个转换，很容易就足够快了。 模拟每个可能的游戏序列是不可能的，因为可能的移动指令的数量呈指数增长。 

一些边缘情况可能会破坏粗心的实施。 如果玩家的棋步大于当前的棋步，则该棋步无法使用。 例如：```
5 1
6
7
```正确的输出是：```
Mao Mao nb!
```龙龙无法从一堆 5 号球中取出 6 个球，所以他立即输了。 仅检查集合中是否存在移动而不检查当前桩大小的实现将给出错误的答案。 

另一个棘手的情况是，玩家现在可以移动，但每个结果状态都会给对手一个获胜位置。 例如：```
1 1
1
1
```正确的输出是：```
Long Long nb!
```龙龙拿走了唯一的一个球，毛毛动弹不得。 该算法必须评估未来的位置，而不仅仅是当前玩家是否至少有一个合法的动作。 

当两个玩家具有相同的走法时，就会出现第三种重要情况。 获胜者不是通过比较牌组来决定的，因为第一名玩家的优势仍然取决于当前牌堆的大小。 例如：```
2 1
1
1
```正确的输出是：```
Mao Mao nb!
```龙龙拿走一球，留下一球给毛毛，毛毛拿走并获胜。 

## 方法

 一种直接的方法是递归地探索博弈树。 对于每个状态，我们都会尝试当前玩家的每一个合法动作。 如果任何一步让对手陷入失败状态，则当前玩家获胜。 这是正确的，因为考虑了所有可能的游戏延续。 

问题在于重复状态的数量。 通过许多不同的移动顺序可以出现相同的桩尺寸。 如果没有记忆，递归可以以指数方式多次重新访问相同的位置。 即使有记忆，自然状态也有两种可能的玩家回合和最多 5000 个堆大小，因此动态规划是组织计算的正确方法。 

关键的观察是整个历史都是无关紧要的。 唯一需要的信息是剩余的球数以及轮到谁了。 我们可以按堆大小的递增顺序计算这些状态。 由于每次移动都会减少桩的大小，因此每次转换都指向一个已经解决的状态。 

让`winL[x]`意味着龙龙可以赢，当有`x`球，轮到他了。 让`winM[x]`意味着毛毛可以赢`x`球，轮到他了。 

对于龙龙来说，如果存在合法的驱逐，使毛毛处于失败状态，那么一个国家就是胜利：`winL[x] = true`如果有一些`a`满足`a <= x`和`winM[x-a] = false`。 

同样的想法也适用于毛毛：`winM[x] = true`如果有一些`b`满足`b <= x`和`winL[x-b] = false`。 

基态是`0`球。 零球的玩家无法移动，因此该玩家立即失败。 这意味着两者`winL[0]`和`winM[0]`是假的。

 ## 算法演练

 1. 创建两个动态规划数组。`winL[i]`存储 Long Long 是否获胜`i`在他移动之前的球，以及`winM[i]`存储毛毛是否获胜`i`在他移动之前的球。 这两个值一开始都是 false，因为没有球的球员无法移动。 
2. 处理桩尺寸`1`到`n`。 对于每个尺寸，尝试龙龙可以采取的每一个动作。 如果移动不大于当前的一堆并且由此产生的MaoMao状态正在失败，则标记`winL[i]`是真的。 这遵循正常的游戏规则，一着棋就够了。 
3. 对于相同的牌堆大小，尝试毛毛可用的每一步棋。 如果龙龙的一步棋处于失败状态，标记`winM[i]`是真的。 
4. 计算完所有状态后，检查`winL[n]`。 如果真是这样，龙龙就能强行取得胜利。 否则毛毛就能强行获胜。 

为什么它有效：

 动态规划的不变性是当我们计算状态时`i`，每个可能的下一个状态都已被计算，因为每次移动都会减少桩的大小。 为了让玩家获胜，必须存在至少一招导致对手无法强行获胜的状态。 转换精确地检查这些可能性，因此每个状态都被正确分类。 由于最初的游戏只是龙龙的回合`n`球，`winL[n]`给出了答案。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    win_l = [False] * (n + 1)
    win_m = [False] * (n + 1)

    for i in range(1, n + 1):
        for x in a:
            if x <= i and not win_m[i - x]:
                win_l[i] = True
                break

        for x in b:
            if x <= i and not win_l[i - x]:
                win_m[i] = True
                break

    if win_l[n]:
        print("Long Long nb!")
    else:
        print("Mao Mao nb!")

if __name__ == "__main__":
    solve()
```两个数组代表两个不同玩家的回合。 保持单独的阵列是必要的，因为相同的堆大小可能会导致一个玩家获胜，而另一个玩家由于移动设置不同而失败。 

循环从小堆向上到较大堆。 计算时`win_l[i]`, 每个州`win_m[i - x]`已经知道，因为`i - x < i`。 同样的性质也适用于毛毛的国家。 

条件`x <= i`是防止非法搬迁的边界检查。 早期的`break`只是一种优化。 一旦找到获胜的棋步，检查其他棋步就无法改变结果。

 ## 边缘情况

 对于 Long Long 没有可用的移动的情况，转换正确地离开`winL[n]`错误的。 在输入中：```
5 1
6
7
```唯一的 Long Long 移动是 6，它大于 5。该算法会跳过它，因为`x <= i`是假的，所以国家仍然处于亏损状态。 

对于两个玩家具有相同动作的情况，算法不会基于对称性做出假设。 在：```
2 1
1
1
```对于轮到的玩家来说，拥有一球的状态是获胜状态，但是拥有两个球的状态是失败的，因为第一个玩家必须给对手一球获胜状态。 

对于移动移除所有剩余球的状态，算法通过基本情况来处理它。 如果玩家移除整堆，则对手达到状态`0`，正在丢失。 这使得这一举动正确地显示为获胜的过渡。
