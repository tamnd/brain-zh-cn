 ## 解决方案
 ## 问题理解

 我们有`m`天。 每天都有一组特定的朋友可用，我们必须准确地选择当天的一个可用朋友。 

分配必须满足公平条件。 让`limit = ceil(m / 2)`。 选择的朋友不得超过`limit`整天的时间。 

对于每一天，输入都会提供当天可以玩的朋友列表。 我们的任务是要么构造一个有效的分配，要么确定不存在。 

约束是解决方案不能复杂的第一个线索。 所有测试用例的总天数最多为`100000`，并且所有列表中的可用性条目总数最多为`200000`。 这意味着我们应该寻求一种仅处理每个可用性列表固定次数的解决方案。 任何指数都是不可能的，甚至二次工作`m`会超出限制。 

棘手的部分是选择不是独立的。 今天选择一个朋友会影响我们明天是否仍然可以使用该朋友而不违反最大频率限制。 

一些边缘情况值得关注。 

考虑这样一种情况，每天只有一个可用的朋友：```
m = 3

Day 1: {1}
Day 2: {1}
Day 3: {1}
```唯一可能的任务是朋友`1`三次。 自从`ceil(3/2)=2`，朋友`1`将选择超过允许的限制。 正确答案是`NO`。 

另一个微妙的情况是，当一个朋友出现在许多列表中时，但这些列表还包含替代项：```
m = 5

{1}
{1,2}
{1,2}
{1,3}
{1,4}
```总是选择第一个可用朋友的贪婪策略会选择朋友`1`五次并失败。 通过将一些灵活的日子重新分配给其他朋友，就存在有效的分配。 

最后一个重要的场景是，在初始分配后，恰好有一个朋友超出了限制：```
m = 6

{1}
{1}
{1}
{1,2}
{1,3}
{1,4}
```这里`limit = 3`。 朋友`1`前三天是强制的，最初将在所有六天选择。 我们必须认识到，只有具有多个选项的日子才能重新分配。 如果这样的日子足够多，答案是可能的。 如果没有，那是不可能的。 

## 方法

 暴力解决方案将尝试所有可能的分配。 每天，选择一位可用的朋友并递归地继续。 如果一天最多包含`n`候选人，搜索空间大致变成$$\prod_{i=1}^{m} k_i$$这是天数的指数。 即使只有二十天，每天两个选项，也已经有超过一百万个作业需要检查。 长达十万天，这种做法是完全行不通的。 

关键的观察来自于询问什么实际上会导致失败。 

假设我们最初将每天分配给其空闲列表中的第一个朋友。 计算每个朋友被选择的次数。 

如果没有朋友超过`ceil(m/2)`，我们已经完成了。 

现在假设有一个朋友`x`超过限制。 可以有多个好友同时超过限制吗？ 

不会。如果两个不同的朋友各自出现的次数超过`m/2`次，它们的总出现次数将超过`m`，这是不可能的，因为只有`m`天。 

这极大地简化了问题。 最多有一位朋友可以违反该限制。 

假设朋友`x`被选择了太多次。 唯一的办法就是减少`x`的计数是更改当前分配的天数`x`。 与一位有空的朋友相处的日子无法更改。 空闲列表包含其他朋友的日子可以重新分配给其他人。 

所以策略就变成了：

 1. 最初将每天分配给第一个列出的朋友。 
2. 寻找是否有朋友`x`超过限制。 
3. 如果没有，请回答`YES`。 
4. 否则，重复移动分配的灵活天数`x`联系另一个有空的朋友，直到`x`的计数下降到极限。 
5. 如果我们在达到限制之前用完了灵活天数，请回答`NO`。 

这样做的原因是，只有一个朋友可能会出现问题，并且离开该朋友一天永远不会造成新的违规，因为每个其他朋友的计数只会从最多已经达到限制的值开始增加。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数递归/状态 | 太慢了 |
 | 最佳| O(Σkᵢ) | O(m + n) | 已接受 |

 ## 算法演练

 1.让`limit = (m + 1) // 2`。 
2. 对于每一天，首先选择当天的空闲列表中列出的第一个朋友。 
3. 统计每个好友当前被选中的次数。 
4. 找一个朋友`x`其计数超过`limit`。 
5. 如果不存在这样的朋友，则打印`YES`以及当前的任务。 
6. 否则，计算```
excess = count[x] - limit
```这是必须从好友中移走的选择数量`x`。 
7.全天扫描。 

如果当前指定一天`x`并且这一天至少有两个可用的朋友，将这一天重新分配给任何其他可用的朋友，例如列表中的第二个朋友。 
8. 每次重新分配后，减少`excess`一个。 
9.停一次`excess`变为零。 
10.如果`excess`经过几天的检查仍然呈阳性，打印`NO`。 
11. 否则打印`YES`以及最后的作业。 

### 为什么它有效

 初始分配可能会违反最多一位好友的限制。 让那个朋友成为`x`。 

每个有效的解决方案都必须减少次数`x`被精确地选择`count[x] - limit`。 唯一可以提供帮助的日子是分配给`x`有多种可用选择。 重新分配任何此类日期都会减少`x`数到一。 

任何重新分配都不会造成新的违规。 修改前，各位小伙伴除了`x`最多已经出现`limit`次。 在此过程中，我们增加了它们的计数，但增加的总数正是`x`超出了限制。 一次`x`达到极限后，其他朋友最多还是极限。 

因此，如果存在足够的灵活天数，施工就会成功。 如果没有足够的灵活天数，则不存在任何解决方案，因为所需的减少`x`是不可能的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())

        days = []
        ans = []
        cnt = [0] * (n + 1)

        for _ in range(m):
            arr = list(map(int, input().split()))
            k = arr[0]
            friends = arr[1:]

            days.append(friends)

            chosen = friends[0]
            ans.append(chosen)
            cnt[chosen] += 1

        limit = (m + 1) // 2

        bad = -1
        for friend in range(1, n + 1):
            if cnt[friend] > limit:
                bad = friend
                break

        if bad == -1:
            print("YES")
            print(*ans)
            continue

        need = cnt[bad] - limit

        for i in range(m):
            if need == 0:
                break

            friends = days[i]

            if ans[i] == bad and len(friends) > 1:
                cnt[bad] -= 1
                ans[i] = friends[1]
                need -= 1

        if need > 0:
            print("NO")
        else:
            print("YES")
            print(*ans)

solve()
```实现几乎直接遵循证明。 

每个空闲列表中的第一个朋友将成为临时指派。 这很重要，因为它为我们提供了一个具体的起点，并保证只有一个朋友会成为问题。 

统计频率后，我们找到计数超过限制的好友。 如果不存在这样的朋友，则当前分配已经有效。 

当存在有问题的朋友时，我们仅检查当前分配给该朋友的天数。 仅有单一可用选项的日子无济于事，因为改变它们是不可能的。 对于灵活的一天，分配列表中的第二个朋友就足够了。 我们不需要寻找最好的替代者，因为证据表明减少有问题的朋友的数量是唯一重要的事情。 

变量`need`准确跟踪有多少选择必须从过度使用的朋友那里移走。 一旦达到零，分配就满足频率约束。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(Σkᵢ) | 每个可用性列表被读取一次，并且每天最多被扫描一次 |
 | 空间| O(m + n) | 存储分配、计数和可用性列表 |

 所有测试用例的可用性条目总数最多为`200000`，因此线性处理很容易满足两秒的限制。 内存使用量也大大低于限制，因为我们只存储输入列表和一些辅助数组。

 ## 边缘情况

 考虑完全强制的情况：```
1
1 3
1 1
1 1
1 1
```极限是`2`。 朋友`1`被选了3次。 每天只包含一个候选者，因此算法找不到符合重新分配条件的一天。 剩余的多余部分为正，答案为`NO`。 任何有效的解决方案都需要减少朋友`1`的数，这是不可能的。 

考虑一个可以修复过度使用的友元的情况：```
1
3 5
1 1
2 1 2
2 1 2
2 1 3
2 1 3
```极限是`3`。 初始任务选择好友`1`五次。 超出部分等于`2`。 该算法重新分配远离朋友的两天灵活时间`1`，将其计数精确减少到`3`。 生成的分配是有效的。 

考虑边界情况：```
1
2 5
1 1
1 1
1 1
1 2
1 2
```极限是`3`。 朋友`1`已经出现了三次。 由于计数并不严格大于限制，因此算法不执行任何修改并立即输出`YES`。 这避免了将平等视为侵犯的常见错误。 

最后，考虑：```
1
4 6
1 1
1 1
1 1
2 1 2
2 1 3
2 1 4
```极限是`3`。 朋友`1`最初出现六次，所以多余的是`3`。 恰好存在三天灵活的日子，重新分配这三天会减少朋友`1`到极限。 该算法成功了，表明每个灵活的事件都可以独立使用来删除一个多余的单位。
