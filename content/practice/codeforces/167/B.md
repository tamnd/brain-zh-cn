 ## 解决方案
 ## 问题理解

 考虑到您赢得每场比赛的机会以及您可能获得的奖品类型，我们需要计算在一系列巫师比赛中表现良好的概率。 有 _n_ 场比赛，对于每场比赛，你都知道自己获胜的概率以及奖品是巨奖还是可以装一定数量巨奖的袋子。 你从家里的一个袋子开始，里面可以装_k_个巨额奖品。 目标是计算您至少赢得 _l_ 场比赛的概率，同时能够使用您开始使用的包和赢得某些比赛而获得的任何包来携带您赢得的所有巨额奖品。 

输入以百分比形式给出概率，需要将其转换为小数进行计算。 输出是高精度的实数概率。 这些约束足够严格，以至于对于上限 n=200 而言，对所有可能获胜子集 (2^n) 进行暴力枚举是不可行的。 必须仔细组合概率，考虑到您赢得的奖品以及是否可以存储它们。 

当所有奖品都是袋子时，就会出现微妙的边缘情况。 例如，如果每次比赛都奖励一个袋子，那么您永远不可能赢得巨额奖金，但获胜的比赛数量仍然可能满足_l_。 如果代码天真地假设获胜总是会增加存储需求，则它可能会计算出不可能的场景。 另一个边缘情况是当 _k_ 已经足以持有任意数量的巨奖时； 该守则仍必须强制规定赢得比赛的最低数量。 

## 方法

 暴力方法是枚举您可能赢得的所有比赛子集，计算每个子集的巨额奖品总数和袋子总容量，检查该子集是否满足“至少 _l_ 获胜”和“所有奖品适合”条件，并对每个有效子集的概率求和。 这个方法原则上是正确的，但是在最坏的情况下需要2^n次运算，这对于n=200来说是完全不可行的。 

关键的见解是将其视为一个动态规划问题，涉及已处理的比赛数量、迄今为止获胜的数量以及所获得的巨额奖金总额。 因为袋子的容量可以被视为一种非递减资源，所以我们可以定义一个DP表，其中的状态代表在给定一定数量的获胜和一定数量的比赛的情况下可以存储的最大奖品数量。 对于每场比赛，我们都会根据获胜或失败的概率更新 DP 表，并相应地调整总容量。 通过按顺序迭代竞赛并有效更新状态，我们可以将指数复杂度降低到多项式复杂度，特别是 O(n*k^2)，这在问题约束下是可行的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(1) | O(1) | 太慢了|
 | 动态规划| O(n * k * n) | O(n * k * n) | O(n * k) | 已接受 |

 ## 算法演练

 1. 将所有概率从百分比转换为 0 到 1 之间的小数。这简化了乘法并避免整数缩放错误。 
2.初始化2D DP表`dp[w][c]`， 在哪里`w`是赢得比赛的次数，`c`是目前可以携带的巨奖数量。 放`dp[0][k] = 1.0`，由于考虑零场比赛，您的胜利为零，并且可以携带初始的主场包容量`k`概率为 1。 
3. 迭代每场比赛。 对于每场比赛，准备一个新的 DP 表`next_dp`具有相同的尺寸。 
4. 对于每个现有的 DP 状态`(wins, capacity)`，考虑一下如果您没有赢得比赛的结果。 获胜次数保持不变，容量不变，概率乘以输掉这场比赛的机会。 
5. 中奖结果，中奖次数加1。如果奖品是一个袋子，则将其容量添加到当前容量； 如果奖品是巨额奖品，请将可用容量减1（或确保容量足以容纳）。 通过乘以赢得比赛的机会来更新概率。 仅当新容量非负时才允许此转换。 
6. 处理完所有比赛后，将所有获胜次数至少为 的 DP 状态的概率相加`l`并且容量是非负的。 这个总和就是期望的概率。 

工作原理：DP 表以前向迭代的方式详尽地解释了胜利和可用容量的所有组合。 每个转换都遵循概率和存储限制。 因为我们一次只推进一场比赛，所以我们避免了计数过多，并正确地累积了每个可行结果的概率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, l, k = map(int, input().split())
p = list(map(int, input().split()))
a = list(map(int, input().split()))

p = [x / 100.0 for x in p]

dp = [[0.0 for _ in range(201 + 200)] for _ in range(n + 1)]
dp[0][k] = 1.0

for i in range(n):
    next_dp = [[0.0 for _ in range(201 + 200)] for _ in range(n + 1)]
    for wins in range(i + 1):
        for cap in range(201 + 200):
            if dp[wins][cap] < 1e-15:
                continue
            # Losing this contest
            next_dp[wins][cap] += dp[wins][cap] * (1 - p[i])
            # Winning this contest
            new_wins = wins + 1
            if a[i] == -1:
                if cap > 0:
                    next_dp[new_wins][cap - 1] += dp[wins][cap] * p[i]
            else:
                next_dp[new_wins][cap + a[i]] += dp[wins][cap] * p[i]
    dp = next_dp

result = 0.0
for wins in range(l, n + 1):
    for cap in range(201 + 200):
        result += dp[wins][cap]

print(f"{result:.12f}")
```该代码首先将输入百分比转换为小数以简化乘法。 DP 桌子的尺寸可容纳所有可能的容量，包括比赛中奖励的袋子的增长。 转换正确处理获胜和失败，仅在可行时更新能力。 最终的概率和考虑了满足最低获胜要求的所有状态。 

## 工作示例

 样本1：`3 1 0`,`10 20 30`,`-1 -1 2`| 我| 胜利| 帽 | dp[胜][上限] |
 | ---| ---| ---| ---|
 | 0 | 0 | 0 | 1.0 |
 | 0 | 0 | 0 | 输掉 10% → 0.9，赢得 10% 巨大 → 由于 cap=0 被跳过 |
 | 1 | 1 | 2 | 赢得第三袋 → 0.3 |

 DP 正确地识别出只有赢得第三场比赛才是可行的，总和为 0.3。 

样本2：`1 1 0`,`100`,`1`DP 从 dp[0][0] = 1 开始。赢得唯一一场比赛会得到一个袋子，将容量增加到 1。获胜次数=1，满足`l=1`，总概率=1.0。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n^2 * max_cap) | O(n^2 * max_cap) | 每场比赛最多可重复 n 场胜利，最大容量可达 400 个（初始 k 加上所有袋子容量的总和）|
 | 空间| O(n * max_cap) | O(n * max_cap) | 同时存储两个大小为 (n+1) x (max_cap) 的 DP 表 |

 假设 n ≤ 200 且 max_cap ≤ 400，则 n^2 * max_cap ≈ 1600 万次操作，这完全符合 2 秒的时间限制。
