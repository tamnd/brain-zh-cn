 ## 解决方案
 ## 问题理解

 该任务是将数组重新排列为排序顺序，但限制允许的交换。 给定一个整数序列，只有当其中至少一个是“幸运”数字时才允许交换两个元素，这意味着它的十进制表示仅由数字 4 和 7 组成。 

目标不是找到已排序的数组本身，而是确定它是否可以根据此规则进行排序，如果可以，则输出实现它的交换序列。 交换次数最多允许为数组大小的两倍，但您可以自由输出该范围内的任何有效序列。 

输入是单个数组。 输出是索引之间交换操作的列表，如果在约束下不可能排序，则输出为 -1。 

只允许涉及至少一个幸运数字的交换的约束立即产生了结构性限制：不幸运的元素不能直接在它们之间交换。 只有能够通过幸运元素“路线”，它们才能移动。 

从复杂度的角度来看，数组大小最多可达 10^5 左右。 这立即排除了任何 O(n^2) 交换模拟或朴素的冒泡排序风格方法。 任何有效的解决方案都必须依赖于 O(n log n) 或 O(n) 预处理，然后依赖于线性数量的交换操作。 

当根本没有幸运数字时，就会出现微妙的失败情况。 例如，如果数组是`[3, 2, 1]`，任何元素都不能与其他任何元素交换，因为每次交换都需要至少一个幸运数字。 正确的输出是`-1`除非数组已经排序。 

另一个边缘情况是幸运数字存在但不足以连接排列结构。 例如，如果只存在一个幸运元素，那么它就像一个中心，每个非幸运元素都必须通过它移动。 “至少有一个幸运数字就足够了”这一天真的想法在可行性上是正确的，但前提是我们能够在不打破索引限制的情况下真正通过它进行互换。 

## 方法

 蛮力视角从直接模拟交换开始。 人们可以尝试运行标准排序算法，例如选择排序或冒泡排序，但将交换限制为有效对。 每次我们发现两个乱序的元素时，我们都会尝试在允许的情况下交换它们。 

这种方法在精神上是正确的，因为它模仿了已知的正确排序过程。 问题在于互换的限制。 当两个元素都不幸运时，直接交换是被禁止的，因此我们需要通过幸运元素进行中间交换。 简单地模拟这一点意味着可能会多次来回移动元素，在最坏的情况下，每次反转修复可能需要 O(n) 次操作，从而导致总交换次数为 O(n^2)。 

关键的观察结果是，幸运元素的行为就像通用中介一样。 如果存在至少一个幸运元素，我们可以将其用作缓冲区，以使用恒定数量的允许交换来实现任意位置之间的任何交换。 这将问题从约束排序问题转变为具有固定“辅助节点”的标准排列排序问题。 

如果至少有一个幸运索引，我们就选择一个这样的索引`h`。 然后任意交换`(i, j)`可以使用以下方法进行模拟：

 交换（i，h），交换（j，h），交换（i，h）。 这是有效的，因为每个单独的交换都涉及幸运元素`h`，满足约束条件。 

一旦可以进行任意交换，问题就简化为通过索引排列对数组进行排序：计算目标排序顺序并将排列分解为循环。 每个周期都可以使用辅助索引的交换来修复。 这最多保证`n + cycles`互换，很容易适合`2n`边界。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 直接约束模拟 | O(n²) | O(n) | 太慢了|
 | 循环分解与幸运枢轴| 由于排序 | O(n log n) O(n) | 已接受 |

 ## 算法演练

 1. 识别所有包含幸运数字的索引。 如果不存在，请检查数组是否已排序。 如果没有排序，则任务无法完成，因为没有交换是合法的。 此步骤隔离了问题中唯一的结构性障碍。 
2. 选择任意一项幸运指数`h`作为辅助枢轴。 该索引将用于调解所有掉期。 该选择不会影响正确性，因为每次交换只要求至少有一个元素是幸运的，并且`h`对于涉及它的所有操作都满足这一点。 
3. 创建数组的排序版本并将每个值映射到其目标位置。 我们还构建了一个排列，描述每个当前索引应按排序顺序移动的位置。 这将问题转化为将排列重新排列为恒等式。 
4. 将这个排列分解为循环。 每个周期代表一组索引，它们必须相互旋转才能到达正确的位置。 一个周期的长度`k`需要`k-1`标准排序逻辑中的交换。 
5.对于每个循环，使用辅助索引`h`模拟通常在周期成员之间进行的交换。 我们反复将元素置于相对于的正确位置`h`，有效地将循环旋转到位。 
6. 将每个模拟交换记录为一对索引。 每个逻辑交换都扩展为恒定数量的实际允许的交换，涉及`h`，保证约束下的合法性。 

### 为什么它有效

 辅助索引`h`充当满足掉期约束的有担保中介。 任何违反规则的交换都会被固定的有效交换序列所取代，从而保留交换两个元素的效果。 由于循环分解保证解析所有循环会产生排序排列，并且每个循环只能使用有效的交换模拟来解析，因此该过程永远不会卡住。 不变的是，在处理每个循环之后，到目前为止放置的所有元素都已经处于其最终排序位置，并且永远不会再次移动。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_lucky(x):
    s = str(x)
    return all(c in "47" for c in s)

n = int(input())
a = list(map(int, input().split()))

sorted_a = sorted(a)

# find any lucky index
lucky_idx = -1
for i, v in enumerate(a):
    if is_lucky(v):
        lucky_idx = i
        break

if lucky_idx == -1:
    if a == sorted_a:
        print(0)
    else:
        print(-1)
    sys.exit()

# build value -> sorted positions (handle duplicates carefully)
pos = {}
for i, v in enumerate(sorted_a):
    pos.setdefault(v, []).append(i)

target = [0] * n
for i, v in enumerate(a):
    target[i] = pos[v].pop()

visited = [False] * n
ops = []
h = lucky_idx

for i in range(n):
    if visited[i] or target[i] == i:
        visited[i] = True
        continue

    cycle = []
    cur = i
    while not visited[cur]:
        visited[cur] = True
        cycle.append(cur)
        cur = target[cur]

    # fix cycle using helper h
    for j in range(1, len(cycle)):
        u = cycle[j]
        v = cycle[0]
        if u == h or v == h:
            ops.append((u + 1, v + 1))
        else:
            ops.append((u + 1, h + 1))
            ops.append((v + 1, h + 1))
            ops.append((u + 1, h + 1))

print(len(ops))
for x, y in ops:
    print(x, y)
```解决方案首先检查是否存在任何幸运元素，因为没有它就不可能进行交换。 如果不存在，则仅当数组已排序时才能进行排序。 

之后，该数组被映射到一个排列，描述每个元素应按排序顺序排列的位置。 这一步至关重要，因为它将问题转化为循环解决而不是直接的值操纵。 

循环处理循环确保每个索引仅被访问一次。 然后使用辅助索引修复每个周期。 交换扩展是关键的实现细节：当所需交换的两个端点都不是助手时，我们通过三个操作来路由它。 这保证了每个记录的交换在问题约束下都是有效的。 

最终输出是允许的交换序列，其长度保持在允许的范围内，因为每个大小为 k 的循环都会产生 O(k) 次操作。

 ### 示例 1

2

```两个数字都已按顺序排列。 

| 步骤| 数组| 幸运指数| 行动| 行动|
 | ---| ---| ---| ---| ---|
 | 初始化| [4,7]| 0 | 已经排序 | 0 |

 该算法检测到没有需要校正的周期，因此不会生成交换。 

### 示例 2

 输入：```
3
4 2 1
```| 步骤| 数组| 找到循环 | 行动| 行动|
 | ---| ---| ---| ---| ---|
 | 开始 | [4,2,1]| (0 2 1) | 工艺循环| 通过助手进行 3 次交换 |

 循环结构显示索引 0 → 2 → 1 → 0。辅助索引为 0，因为值 4 是幸运的。 通过通过索引 0 路由交换来解决该循环，最终将所有元素按排序顺序排列`[1,2,4]`。 

这表明，即使目标涉及移动幸运元素本身，它仍然可以作为稳定的枢轴，因为它参与交换，但在同一周期内恢复到正确的位置。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def is_lucky(x):
        return all(c in "47" for c in str(x))

    n = int(input())
    a = list(map(int, input().split()))
    sorted_a = sorted(a)

    lucky_idx = -1
    for i, v in enumerate(a):
        if is_lucky(v):
            lucky_idx = i
            break

    if lucky_idx == -1:
        return "0\n" if a == sorted_a else "-1\n"

    pos = {}
    for i, v in enumerate(sorted_a):
        pos.setdefault(v, []).append(i)

    target = [0] * n
    for i, v in enumerate(a):
        target[i] = pos[v].pop()

    visited = [False] * n
    ops = []
    h = lucky_idx

    for i in range(n):
        if visited[i]:
            continue
        cur = i
        cycle = []
        while not visited[cur]:
            visited[cur] = True
            cycle.append(cur)
            cur = target[cur]

        for j in range(1, len(cycle)):
            u, v = cycle[j], cycle[0]
            if u == h or v == h:
                ops.append((u, v))
            else:
                ops.append((u, h))
                ops.append((v, h))
                ops.append((u, h))

    out = [str(len(ops))]
    out += [f"{x+1} {y+1}" for x, y in ops]
    return "\n".join(out) + "\n"

# custom cases

assert run("3\n4 2 1\n") != "", "basic cycle case"
assert run("3\n1 2 3\n") == "0\n"

 ## 边缘情况

 当没有幸运数字时，算法立即检查数组是否已排序。 对于像这样的输入`[3,2,1]`，检查失败，输出为`-1`，因为没有交换是合法的。 

当恰好有一个幸运元素时，比如`[47, 5, 1]`，该元素成为唯一的帮助者。 排列被正常分解，并且每个交换都通过索引 0 进行路由。即使幸运元素参与交换，循环结构也保证它在循环结束时返回到正确的位置。 

当所有元素都幸运时，每次交换都直接有效。 该算法仍然有效，但退化为标准循环排序，不需要通过助手进行路由。
