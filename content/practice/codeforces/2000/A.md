 ## 解决方案
 ## 问题理解

 我们得到了写在板上的整数列表，其中一个可能是以下形式的数字的损坏表示$10^x$在哪里$x \ge 2$。 发生损坏是因为幂符号“^”丢失。 例如，$10^5$可能被写成$105$和$10^{19}$作为$1019$。 我们的任务是确定棋盘上的每个数字是否可能是十的幂的损坏版本。 如果可以，我们打印“YES”； 否则，我们打印“NO”。 

输入大小最多允许 10,000 个整数，每个整数不超过 10,000。 这个上限很小，这立即表明我们可以预先计算所有潜在的有效数字并对每个整数执行简单的成员资格检查，而不是进行复杂的算术转换。 问题的微妙之处在于正确解释什么算作损坏的$10^x$：数字必须以 10 开头，然后直接连接指数的数字，而不是任意数字。 例如，1010 可以对应于$10^{10}$，但 100 或 1023 则不能。 

可能会导致简单解决方案失败的边缘情况包括像 100 这样的数字（即$10^2$） - 自从$x \ge 2$，腐败可能产生 102，但不是 100。同样，像 1002 这样的数字应该仔细解释：它代表$10^2$附加“2”作为指数，但 1002 本身并不对应于有效的损坏形式，因为指数需要为 2 但数字不匹配。 小数字、带有多个前导零的数字以及接近 10,000 限制的数字是潜在的陷阱。 

## 方法

 暴力方法将尝试重建$10^x$为所有人$x \ge 2$，将它们转换为字符串，通过删除“^”符号来模拟损坏，然后将每个损坏的数字与输入列表进行比较。 虽然这对于单个整数是可行的，但对于 10,000 个整数和可能非常大的指数这样做效率很低。 具体来说，检查所有$x$比如说，1,000,000 是不必要的，因为我们的整数以 10,000 为界。 

关键的观察是棋盘上的最大整数是 10,000，这意味着最大的整数$10^x$在此范围内可能产生损坏的数字是$10^2 = 100$最多$10^4 = 10000$。 更一般地说，如果我们枚举$x$从 2 开始，通过连接“10”和数字来形成损坏的数字$x$，我们可以预先计算 1 到 10,000 范围内所有可能的有效数字。 然后，对于每个输入数字，我们只需检查它是否存在于这个预先计算的集合中。 这将问题简化为每个数字的恒定时间查找，并且速度非常快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（检查每个 x 的每个 a）| O(t * max_x) | O(t * max_x) | O(1) | O(1) | 如果 max_x 大则太慢 |
 | 预先计算有效的损坏数字 | O(max_x + t) | O(max_x) | 已接受 |

 ## 算法演练

 1. 初始化一个空集来存储所有可能被破坏的数字$10^x$和$x \ge 2$并且结果数 ≤ 10,000。 我们使用集合进行 O(1) 成员资格检查。 
2. 迭代$x$从2开始，转换$x$到一个字符串，并将其与“10”连接以模拟损坏的数字。 将此连接字符串转换回整数。 
3. 如果结果整数大于 10,000，则中断循环，因为更大$x$只会产生更大的数字，这些数字超出了输入范围。 
4. 将每个有效整数添加到集合中。 
5. 对于每个输入整数，检查它是否存在于预先计算的集合中。 如果是，则打印“YES”； 否则，打印“NO”。 

这是有效的，因为损坏是确定性的：有效数字必须始终以“10”开头，后跟代表指数的数字。 通过预先计算输入约束内的所有可能性，我们保证正确性并避免不必要的计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
numbers = [int(input()) for _ in range(t)]

valid_set = set()
x = 2
while True:
    corrupted = int("10" + str(x))
    if corrupted > 10000:
        break
    valid_set.add(corrupted)
    x += 1

for a in numbers:
    if a in valid_set:
        print("YES")
    else:
        print("NO")
```我们首先将所有输入读取到列表中。 预计算循环通过将“10”与从 2 开始的每个指数连接起来，直到结果数字超过 10,000，构建所有有效损坏数字的集合。 在最后的循环中，我们利用集合的 O(1) 查找来有效地确定成员资格。

 ## 边缘情况

 对于最小可能的指数 x = 2，损坏的数字为 102。该算法在集合中包含 102，确保输入“102”被正确识别为“YES”。 对于略高于 10,000 限制的数字（例如 10002），预计算循环会在包含它们之前停止，因此算法会正确返回“NO”。 基于集合的查找保证重复的数字或无序的输入不会影响正确性。 损坏数字的确定性形成确保不会遗漏任何有效数字。
