[CF 2000D - 右左错误](https://codeforces.com/problemset/problem/2000/D)

 **标签：** 贪婪、实现、两个指针
 **求解时间：** 6m 4s
 **已验证：** 否

 ## 解决方案
 ## 问题理解

 我们有一行细胞。 每个单元格包含一个正值`a[i]`和一个字符，或者`L`或者`R`。 

一个操作选择一对位置`(l, r)`和`l < r`，其中位置`l`目前包含`L`和位置`r`目前包含`R`。 我们获得它们之间所有值的总和，包括在内。 之后，区间内的每个位置`[l, r]`变得无法使用。 

由不同操作创建的区间永远不会重叠，因为一旦选择了一个区间，它的所有位置就会从未来的考虑中消失。 

目标是最大化总分。 

这些限制立即表明我们需要接近线性时间的东西。 在所有测试用例中，单元总数最多为`2 · 10^5`，这意味着`O(n)`或者`O(n log n)`解决方案很容易足够快。 一个`O(n²)`方法大致需要`4 · 10^10`在最坏的情况下进行操作，这是完全不可行的。 

主要困难在于选择一个区间会删除许多位置，这会影响以后可以选择哪些区间。 总是采用当前最大可用区间的贪心策略显然并不正确。 

一些边缘情况值得关注。 

考虑：```
3
1 2 3
LLL
```没有`R`根本不。 不存在有效的操作，所以答案是`0`。 

一个粗心的实现，假设每个`L` can be matched would fail here.

Consider:

```
4
5 5 5 5
LRLR
```最优选择是整个区间`[1,4]`, 给予`20`.

Choosing `[1,2]` first gives only `10`, after which `[3,4]` gives another `10`. The total is still `20`, showing that different decompositions can produce the same result.

Now consider:

```
4
1 100 100 1
LRRL
```

The only valid pair using the last `L`是不可能的，因为没有`R`在它的右边。 最好的选择是`[1,3]`， 值得`201`。 

尝试在本地匹配字符而不考虑位置顺序的解决方案可能会错误地计算无效对。 

另一个微妙的情况是：```
5
1 2 3 4 5
RLLLR
```最左边的字符是`R`，所以它永远不能作为左端点。 唯一有用的间隔是`[2,5]`， 值得`14`。 

该算法必须忽略边界处不匹配的字符。 

## 方法

 蛮力的观点是递归地思考。 我们随时可以选择任何有效的对`(l,r)`，获得相应的间隔总和，删除该间隔，然后继续处理剩余的部分。 探索所有可能的选择最终找到最佳方案。 

这是正确的，因为它检查每个合法的操作序列。 

问题在于可能性的数量。 甚至决定首先采用哪个有效间隔也可能涉及`O(n²)`选择，每一个选择都会带来更多的可能性。 搜索空间呈指数级增长，很久以前就变得毫无希望`n = 2 · 10^5`。 

为了更快地找到问题，我们需要了解最佳解决方案是什么样的。 

假设我们选择一个区间`[l,r]`。 里面的每一个位置都消失了。 由于所有值都是正数，因此每当我们可以在不违反端点要求的情况下扩大区间时，获得的分数只会增加。 

这一观察改变了我们看待问题的方式。 想象一下取最左边可用的`L`和最右边可用的`R`。 如果`L`位于之前`R`，然后使用这两个端点捕获所有当前剩余位置中的最大可能间隔。 

删除该间隔后会发生什么？ 里面的每个位置都没有了，所以以后的任何操作都必须完全发生在它之外。 由于我们已经使用了最外面的可能端点，因此剩下的问题与保留在外面的单元格上的问题完全相同。 

这自然就引出了一个两指针的过程。 

将一个指针放在左端，另一个放在右端。 

移动左指针，直至到达`L`。 

移动右指针，直至到达`R`。 

如果左指针仍然在右指针之前，我们应该将它们配对。 因为所有数字都是正数，所以采用最外面的有效对捕获它们之间的每个值，并且不会比将该区域分割成更小的间隔更糟糕。 

某个区间的分数可以通过以下方式获得`O(1)`使用前缀和的时间。 

使用该对后，将两个指针向内移动并重复。 

整个数组仅被扫描一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最优两指针+前缀和| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.构建一个前缀和数组，使得任意区间的和`[l,r]`可以在常数时间内计算出来。 
2.初始化两个指针，`i = 0`和`j = n - 1`。 
3. 移动`i`向右移动，直到它指向`L`或通过`j`。 
4. 移动`j`向左移动，直到它指向`R`或通过`i`。 
5. 如果`i >= j`，没有有效的对剩余，所以停止。 
6. 添加区间总和`[i, j]`使用前缀和得出答案。 
7. 增量`i`并减少`j`。 
8. 重复步骤 3。 

关键操作是第 6 步。一旦剩下最左边的`L`和最右边的剩余`R`找到后，将它们立即配对即可捕获当前剩余段中的最大可能间隔。 由于每个值都是正数，因此从该区间中排除任何单元格只会降低分数。 

### 为什么它有效

 在任何阶段，考虑最左边的剩余`L`和最右边的剩余`R`。 任何有效的操作都必须使用不比该左端点更左的端点`L`和一个右端点不比它更右`R`。 

由这些最外面的有效端点形成的间隔包含可以使用其他剩余端点形成的每个间隔。 由于所有数组值都是正数，因此较大区间的总和至少与其内部任何较小区间的总和一样大。 

选择这个最外层区间后，其内的所有位置都会消失。 任何未来的操作都必须完全超出该区间。 因此，剩下的子问题与我们刚刚采用的间隔无关。 

每一步重复这个论证表明贪婪选择总是安全的，并且算法会产生最大可能的分数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        s = input().strip()

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]

        i = 0
        j = n - 1
        ans = 0

        while True:
            while i < n and s[i] != 'L':
                i += 1

            while j >= 0 and s[j] != 'R':
                j -= 1

            if i >= j:
                break

            ans += pref[j + 1] - pref[i]

            i += 1
            j -= 1

        print(ans)

solve()
```前缀和数组允许在恒定时间内计算间隔和。 区间值`[i, j]`是：```
pref[j + 1] - pref[i]
```两个指针寻找下一个可用的`L`从左边开始，下一个可用`R`从右边。 

使用一对后，两个指针都向内移动。 这有效地从未来的考虑中消除了整个区间，与证明中的贪婪论证相匹配。 

一个容易犯的错误是使用`pref[j] - pref[i]`，这将排除`a[j]`。 另一个常见错误是忘记指针向内移动后必须继续搜索，因为下一个位置可能不是有效的端点。 

Python 整数是无界的，因此不存在溢出问题。 最大可能答案可能比`32-bit`整数限制。

 输入：```
5
1 2 3 4 5
LRLRR
```前缀和：```
[0,1,3,6,10,15]
```| 步骤| 我| j | 间隔 | 增益| 总计 |

此示例演示了原始数组中的间隔不需要不相交。 贪婪进程在剩余的未删除端点上运行，这与预期的游戏完全对应。

 ## 边缘情况

 考虑：```
1
2
3 9
RL
```左指针搜索`L`并找到位置`2`。 右指针搜索`R`并找到位置`1`。 自从`i >= j`，不存在有效区间。 

该算法输出：```
0
```这是正确的。 

考虑：```
1
5
1 2 3 4 5
LLLLL
```右指针永远找不到`R`。 它移过数组的开头，导致`i >= j`。 算法立即终止并返回`0`。 

考虑：```
1
5
1 2 3 4 5
RLLLR
```左指针会跳过第一个字符，因为它是`R`。 最终停在位置`2`，而右指针停在位置`5`。 

所选区间为：```
[2,5]
```具有价值：```
2 + 3 + 4 + 5 = 14
```算法输出`14`，正确忽略不匹配的`R`一开始。 

最后，考虑：```
1
4
5 5 5 5
LRLR
```第一对使用位置`(1,4)`和收获`20`。 向内移动后，其余端点交叉，过程停止。 

输出是：```
20
```它与最大可能得分相匹配，并说明了为什么采用最外面的有效对是最佳的。
