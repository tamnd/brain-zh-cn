 ## 解决方案
 ## 问题理解

 我们有一个由数组表示的书架。 移动会选择书架的一个连续部分，该部分中的每一对书都具有互质值，然后反转整个部分。 任务是决定重复移动是否可以将数组转换为非递减顺序。 

关键是要了解哪些运动实际上是可能的。 反转成对互质值的一段相当于在该段内执行相邻交换。 由于该段中的每个相邻对也是互质的，因此允许互质值之间的每个相邻交换。 长度为二的段给出相反的方向，因此每个允许的相邻交换也可以被视为有效操作。 

输入包含多个测试用例。 每个测试用例都会给出书架上的书籍数量和价值。 输出是初始排列能否达到排序排列。 

约束足够大，检查每对位置是不可接受的。 由于图书总数达到20万左右，二次解在最坏的情况下需要大约4000亿次比较，这远远超出了通常的竞争性编程限制。 我们需要一个接近线性或线性算数的解决方案。 

重要的边缘情况来自不能相互交叉的值。 例如，使用输入```
1
4
6 1 1 1
```输出是`YES`。 值 6 可以右移，因为它与每个 1 互质，因此数组可以排序。 

考虑```
1
4
2 2 6 3
```输出是`NO`。 前2个和后2个的gcd为2，因此它们的相对顺序永远不会改变。 它们相对于彼此已经按升序排列，但 6 和 3 也共享一个因子，并且在排序数组中 6 必须移到 3 之后。 那个穿越是不可能的。 

粗心解决方案的一个更简单的失败案例是：```
1
3
3 2 6
```答案是`NO`。 仅检查某些相邻交换是否可能的解决方案可能会忽略 3 和 6 不能交换，即使中间值与两者互质。 

## 方法

 直接的方法是模拟可能的交换。 我们可以尝试重复查找相邻的互质对，并在提高顺序时交换它们，类似于冒泡排序。 这是正确的，因为执行的每次交换都是合法的。 然而，在最坏的情况下，冒泡排序执行 O(n²) 次交换，这对于 n 大约 200000 来说太慢了。 

有用的观察是，唯一可以改变相对顺序的对是 gcd 等于 1 的对。如果两个值的 gcd 大于 1，它们永远不会变得相邻和交换，因为最后的交叉步骤本身就是非法的。 

这给了我们一个固定的不变量。 每个非互质对必须已经以与其在排序数组中出现的相同相对顺序出现。 我们只需要检测是否存在一对位置 i < j，其中 gcd(a[i], a[j]) > 1 但 a[i] > a[j]。 这样的一对是不可避免的反转。 

剩下的挑战是快速找到这些对。 我们从左到右处理数组，并为每个素数因子保留迄今为止在包含该素数的数字中看到的最大值。 当我们达到值 x 时，与 x 共享质因数的每个先前值都与 x 不互质。 如果其中的最大值大于x，我们就发现了禁止反转。 

10^6 以下的值的不同质因数数量很少，因此更新这些质数桶是高效的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 素因子追踪 | O(n log A) | O(n log A) | O(A) | 已接受 |

 ## 算法演练

 1. 将每个数字分解为其不同的质因数。 我们只需要不同的因子，因为 gcd 大于 1 意味着至少有一个素因子是共享的。 
2. 维护一个数组，其中位置 p 存储迄今为止所见的包含素因数 p 的最大值。 
3. 从左到右扫描书籍。 对于当前值 x，查看其所有素因数。 在这些因子中，找到与 x 共享任何因子的最大先前值。 
4. 如果先前的最大值大于 x，则这两个值形成永远无法固定的反转，因此答案为`NO`。 
5. 检查完 x 后，用值 x 更新 x 的每个质因数，因为未来的位置需要知道 x 已经出现。 

为什么它起作用：素因数的维护最大值代表不能跨越当前值的最差可能的早期值。 任何与当前值共享因子的先前值都将永远锁定在左侧。 如果最大锁定值已经大于当前值，则排序将需要不可能的交换。 如果这种情况从未发生，则每个禁止对都已正确排序，并且所有剩余的反转都涉及互质值，这可以通过允许的交换来解决。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXV = 10**6

spf = list(range(MAXV + 1))
for i in range(2, int(MAXV ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXV + 1, i):
            if spf[j] == j:
                spf[j] = i

def factors(x):
    res = []
    while x > 1:
        p = spf[x]
        res.append(p)
        while x % p == 0:
            x //= p
    return res

fac_cache = {}

def get_factors(x):
    if x not in fac_cache:
        fac_cache[x] = factors(x)
    return fac_cache[x]

def solve_case(a):
    best = [0] * (MAXV + 1)
    for x in a:
        fs = get_factors(x)
        mx = 0
        for p in fs:
            if best[p] > mx:
                mx = best[p]
        if mx > x:
            return "NO"
        for p in fs:
            if x > best[p]:
                best[p] = x
    return "YES"

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ans.append(solve_case(a))
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```筛子计算每个数字的最小质因数，直到最大可能值。 这使得每个因式分解都能快速运行。 

里面的扫描件`solve_case`直接遵循算法。 在将当前值插入质数桶之前，它会检查之前的某个非互质值是否更大。 更新发生在检查之后，因为当前值不能与自身进行比较。 

因子列表仅包含每个素数一次。 如果我们存储重复的因子，结果将是正确的，但速度会更慢。 不同的因数就足够了，因为共享任何素因数就意味着 gcd 不是一个。 

内存使用主要由最小素因子数组和最大值跟踪数组主导。

```扫描的行为如下。 

| 职位| 价值| 之前的共享素数最大值 行动|
 | --- | --- | --- | --- |
 | 1 | 5 | 0 | 插入因子 5 |

 | 职位| 价值| 之前的共享素数最大值 行动|
 | --- | --- | --- | --- |

 结果是`NO`因为6和3不能交叉。

 ## 边缘情况

 对于`1 4 6 1 1 1`，值 6 与任何 1 都没有共享因子。该算法没有发现先前的冲突值，因此它允许该值通过交换向右移动。 

为了`1 4 2 2 6 3`，当处理最终值3时，素因数3已经存储了左侧的值6。 由于 6 大于 3 并且无法与其交叉，因此算法立即拒绝该数组。 

对于具有所有相等值的数组，例如`1 5 4 7 7 7 7`，每个阻塞对都已排序，因为相等的值不会创建反转。 最大共享值永远不会大于当前值，所以答案是`YES`。 

对于单个元素数组，不需要移动。 数组已经排序，算法返回`YES`。
