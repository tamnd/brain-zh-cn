 ## 解决方案
 ## 问题理解

 我们得到了一个类似二进制的序列，但它不是由位组成，而是由两个标签组成：完美和非完美。 序列具有固定长度`n`，并且准确地说`m`其位置必须是完美的，而其余的`n - m`是不完美的。 

对于这些标签的任何有效排列，我们将其得分定义为 PERFECT 的最长连续块的长度。 换句话说，我们查看每一次连续的 PERFECT 条目，并取其中的最大长度。 

任务不是构造一个序列，而是推理满足约束的所有可能序列并确定两个极端：最大可能的最长 PERFECT 运行和最小可能的最长 PERFECT 运行。 

限制很小：两者`n`和`m`最多 1000 个，并且最多有 100 个测试用例。 这立即表明任何明确构建或模拟序列的解决方案都是不必要的。 问题的结构是纯粹的组合，仅取决于我们如何划分`m`相同的项目（完美）分成由非完美分隔的部分。 

一种天真的方法可能会尝试枚举所有位置`m`完美之中`n`位置，即`C(n, m)`配置。 即使是为了`n = 1000`，这是一个天文数字，无法探索。 另一个天真的想法是尝试贪婪地放置完美并模拟所有分布，但这仍然隐含地探索指数排列。 

边缘情况出现时`m = 0`或者`m = n`。 在这些情况下，顺序是固定的：分别是全部不完美或全部完美。 任何解决方案都必须立即识别这些退化配置，否则可能会出现不必要的计算或对空运行的错误推理。 

## 方法

 暴力的观点从生成每个长度的二进制字符串开始`n`恰好与`m`那些（完美）。 对于每个配置，我们计算最长的连续运行`O(n)`时间。 由于有`C(n, m)`这样的配置，总复杂度约为`O(C(n, m) * n)`，即使对于像这样的小输入，这也是远远超出可行的`n = 1000, m = 500`。 

关键的观察是分数仅取决于我们如何划分`m`将相同的项目分成连续的组。 非完美充当分隔符，使我们能够打破完美运行。 所以问题就变成了：给定`m`相同的对象，如果我们允许将它们分布在段之间，最大的组可以有多大或多小？ 

为了获得最高分，我们希望完全避免分割“完美”。 如果我们把所有的`m`连续完美，我们获得单个长度的块`m`。 这显然是最佳的，因为插入其中的任何非完美都会分裂块并且不能增加最大游程长度。 

对于最低分数，我们希望尽可能均匀地分布 PERFECT，这样相邻的块就不会变得太大。 如果我们划分`m`项目进入`n - m + 1`可能的插槽（不完美之间的间隙，包括末端），我们希望将它们尽可能均匀地分布在这些插槽上。 最佳平衡后任何插槽的最大负载决定了最小可能的最长连续运行。 

这简化为经典的负载平衡解释：我们放置`m`无法区分的球进入`k = n - m + 1`桶，最小化最大桶大小。 答案是上限`m / k`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(C(n, m) · n) | O(C(n, m) · n) | O(n) | 太慢了|
 | 最佳| 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 阅读`n`和`m`。 这些定义了我们必须放置多少完美和不完美的元素。 
2. 计算可能的最大分数。 由于将所有 PERFECT 组合在一起总是有效的，因此我们可以形成的最大连续块就是`m`。 
3. 计算可用分隔槽的数量：`k = n - m + 1`。 这对应于当我们以最佳方式交错非完美时可以存在多少个完美片段。 此步骤体现了这样的想法：每个不完美的块都可能分裂一个块，从而增加碎片。 
4. 如果`m = 0`，最大和最小分数均为`0`，因为根本不存在完美的。 
5.如果`m > 0`，通过分布计算最小可能的最大块大小`m`物品尽可能均匀地分布在`k`插槽。 最小可达到的最大负载是`(m + k - 1) // k`。 
6. 输出该对`(smax, smin)`。 

关键的推理步骤是从序列排列到跨时隙分​​布的转换。 一旦完成这种映射，答案就变成了简单的算术计算。 

### 为什么它有效

 任何有效的序列都可以被视为由至少一个非完美分隔的完美交替块，除了可能在末尾处。 这最多创建`n - m + 1`可以放置完美方块的插槽。 最长的连续 PERFECT 运行恰好是分配给任何单个插槽的 PERFECT 的最大数量。 最大化或最小化该最大值会减少到将所有内容折叠到一个插槽中或尽可能均匀地分配项目。 该模型之外的任何安排都无法改变通过非完美分裂所施加的基本界限。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())

        if m == 0:
            print(0, 0)
            continue

        smax = m

        k = n - m + 1
        smin = (m + k - 1) // k

        print(smax, smin)

if __name__ == "__main__":
    solve()
```直接按照推导公式实现。 唯一微妙的情况是`m = 0`，其中通用公式仍然有效，但使推理不太透明，因此它被显式处理。 

价值`smax = m`来自这样的观察：将所有 PERFECT 合并到一个连续的片段中永远不会违反约束。 的计算`k`反映了如果我们插入所有非完美片段作为分隔符，可以存在多少个不相交的完美片段。 天花板除法计算均匀分布相同元素时可能的最紧边界。 

## 工作示例

 我们追踪两个有代表性的案例。 

### 示例 1：`n = 5, m = 4`我们有 4 个完美和 1 个不完美。 

| 步骤| 米 | k = n-m+1 | 最大| 斯敏 |
 | ---| ---| ---| ---| ---|
 | 初始| 4 | 2 | - | - |
 | 计算最大值 | - | - | 4 | - |
 | 计算最小值 | - | - | 4 | (4+2-1)//2 = 2 |

 最大排列为`PPPPN`，给出 4 的运行。最小值是通过将单个 NON-PERFECT 拆分为 PERFECT 来实现的，例如`PPNPP`，产生长度为 2 的游程。 

这证实了非完美充当分离器，在可能的情况下强制分裂。 

### 示例 2：`n = 10, m = 3`| 步骤| 米 | k = n-m+1 | 最大| 斯敏 |
 | ---| ---| ---| ---| ---|
 | 初始| 3 | 8 | - | - |
 | 计算最大值 | - | - | 3 | - |
 | 计算最小值 | - | - | 3 | (3+8-1)//8 = 1 |

 这里有足够的槽，我们可以单独隔离每个 PERFECT，因此最小最长游程变为 1。该结构允许完全分离，这与将稀疏项分布在许多间隙上是一致的。

 ## 边缘情况

 当`m = 0`，根本不存在 PERFECT，因此不可能存在连续的段。 该算法显式返回`0 0`，它与空最大值的定义匹配。 

什么时候`m = n`，所有元素都很完美。 公式给出`smax = n`， 和`k = 1`， 所以`smin = n`。 该算法正确返回单个强制配置。 

什么时候`m = 1`， 不管`n`，只有一个 PERFECT，因此最大值和最小值均为 1。该公式产生`(1 + (n - 1 + 1) - 1) // (n - 1 + 1) = 1`，与单个元素的隔离一致。 

这些案例证实，基于槽的解释在极端密度下仍然有效，在极端密度下，要么不可能分离，要么分离微不足道。
