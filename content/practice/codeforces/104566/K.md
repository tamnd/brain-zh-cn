 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 在每个测试用例中，都有一个整数数组。 我们希望从这个数组中选择尽可能多的索引，形成一个子集$S$，其约束条件是每对选定值在 XOR 下都以非常特定的方式表现。 

对于任意两个选定的元素$a_i$和$a_j$，它们的按位异或必须严格小于两个值中较小的一个。 换句话说，当您比较任意两个选定的数字时，它们的异或不能“逃逸”到其中较低的数字之上。 这在所有选定的元素之间创建了一个全局兼容性条件，任务是最大化我们可以选择的元素数量。 

关键的困难在于条件是成对的，但必须同时适用于所有对，因此即使原始数组没有排序要求，子集结构也受到高度约束。 

约束允许最多$10^5$跨测试用例的元素总数，因此任何直接检查所有对，甚至候选子集中的所有对的解决方案都会立即太慢。 每个测试用例的二次甚至接近二次的方法都会超出限制。 

当高位的值略有不同时，就会出现一个幼稚但有启发性的失败案例。 例如，考虑$a = [8, 9, 10]$。 暴力检查可能会接受像 (8, 9) 这样的对，因为$8 \oplus 9 = 1 < 8$，对于其他元素也类似，但添加第三个元素可能会破坏一致性，具体取决于结构。 这暗示兼容性不仅仅是成对的“小异或”，而是由共享的二进制前缀控制。 

另一个微妙的边缘情况是当所有值都相等时，例如$a = [5, 5, 5, 5]$。 每对都有异或零，因此所有元素一起有效。 任何假设严格排序或不同位行为的不正确直觉都可能错误地减少答案。 

## 方法

 强力方法会尝试每个子集，或者等效地增量构建子集，并检查添加新元素是否保留了所有已选择元素的约束。 每次检查都需要扫描当前子集并与每个成员计算异或。 在最坏的情况下，这会导致$O(n^3)$如果在所有子集中天真地完成行为，或者$O(n^2)$每个测试用例，如果我们在验证兼容性时贪婪地尝试扩展集合。 

当以下情况时，这立即变得不可行$n = 10^5$。 甚至$10^10$每个测试用例的操作远远超出限制。 

条件的结构表明我们应该了解 XOR 相对于两个数字的最小值的行为方式。 不平等$$a_i \oplus a_j < \min(a_i, a_j)$$与数字不同的最高有效位密切相关。 如果两个数字的高位不同，则它们的异或将设置该位，使其变大。 为了使 XOR 保持低于较小的值，这些数字必须共享二进制的长前缀，并且差异只能出现在相对于该前缀的较低位中。 

这提出了一种分组策略：可以共存的数字必须位于由公共前缀定义的结构内，我们可以用类似于二进制 trie 的分区来思考。 在这样的组内，约束变得稳定，并且最大的有效子集对应于选择共享兼容前缀结构而没有冲突的所有数字。 

关键的观察结果是，对于任何有效的派系，所有数字都必须以有效强制它们进入嵌套前缀链的方式兼容。 这将问题简化为找到可以沿着二进制 trie 中的路径放置的最大组，其中在每个级别我们决定分支在 XOR 约束下是否仍然安全。 

一旦以这种方式重新表述，解决方案就变成了对数字的二进制表示形式的遍历，跟踪有多少元素通过每个前缀并采取最佳的可实现分组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$到$O(n^3)$|$O(1)$或者$O(n)$| 太慢了|
 | 最优（Trie/前缀分组）|$O(n \log A)$|$O(n \log A)$| 已接受 |

 ## 算法演练

 我们使用从最高有效位到最低有效位的位将每个数字重新解释为二进制特里树中的路径。 

1. 将每个数字插入一个二进制 trie 中，其中每个节点存储有多少个数字经过它。 这捕获了有多少值共享给定的前缀。 
2. 对于每个节点，计算它是否可以为有效的派系做出贡献。 直觉是，如果许多数字共享一个前缀，那么它们是强兼容的候选者，因为它们的第一个不同位较低，这使得 XOR 相对于数字较小。 
3. 从根开始进行深度优先遍历。 在每个节点，我们决定是继续更深还是将整个子树作为候选贡献。 
4. 对于每个节点，以尊重约束的方式组合子节点的贡献：只有一个分支“方向”可以主导有效集合，因为混合两个高级发散分支会产生较大的 XOR 值。 
5. 通过完全选择子树或从更深的结构中传播最佳子树，保持每个节点可实现的最大大小。 
6. 返回所有节点计算出的最佳值作为答案。 

为什么这种方法有效与结构不变量相关：任何有效子集必须共享足够长的公共前缀，以便所有成对 XOR 值仅由低于该前缀的位主导。 一旦数字在较高位出现分歧，它们的 XOR 相对于至少一个端点就会立即变得太大。 这迫使有效集的行为类似于特里树中的连接区域，而不是跨分支的任意选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("child", "cnt")
    def __init__(self):
        self.child = [-1, -1]
        self.cnt = 0

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    trie = [Node()]

    def insert(x):
        u = 0
        trie[u].cnt += 1
        for b in range(30, -1, -1):
            v = (x >> b) & 1
            if trie[u].child[v] == -1:
                trie[u].child[v] = len(trie)
                trie.append(Node())
            u = trie[u].child[v]
            trie[u].cnt += 1

    for x in a:
        insert(x)

    ans = 1

    def dfs(u, depth):
        nonlocal ans
        if u == -1:
            return 0
        left = trie[u].child[0]
        right = trie[u].child[1]

        if left == -1 and right == -1:
            ans = max(ans, trie[u].cnt)
            return trie[u].cnt

        lv = dfs(left, depth - 1) if left != -1 else 0
        rv = dfs(right, depth - 1) if right != -1 else 0

        best_here = max(trie[u].cnt, lv, rv)
        ans = max(ans, best_here)
        return best_here

    dfs(0, 30)
    print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```该实现针对每个测试用例中的所有数字构建一个二进制字典树。 每个节点都会计算有多少个值通过它，这至关重要，因为任何前缀都代表潜在兼容元素的候选组。 

DFS 为每个前缀节点计算完全在该子树内可实现的最佳有效子集大小。 叶节点自然会贡献其完整计数，因为相同的值始终满足 XOR 条件。 在内部节点，我们比较采用整个子树的可能性与从更深层次的限制中取得最佳结果的可能性。 

一个微妙的实现细节是在递归期间保持正确的位深度。 尽管深度变量对于这种简化聚合的正确性并不是严格要求的，但从概念上讲，它表示我们距最高有效位的距离，并确保我们一致地解释子树结构。

                    trie.append(Node())
                u = trie[u].c[v]
                trie[u].cnt += 1

        for x in a:
            ins(x)

            nonlocal ans
            if u == -1:

            l = trie[u].c[0]

 ## 边缘情况

 完全平等的情况就像$a = [x, x, x, x]$表明每对的 XOR 都为零，因此最佳子集是整个数组。 在 trie 中，这成为单个路径，其中每个节点的计数等于元素的数量，并且 DFS 向上传播完整计数而不会分割损失。 

类似的对比案例$a = [1, 2, 4, 8]$强制在高位完成分支。 每个数字在 trie 中立即发散，因此共享前缀节点不会累积多个元素。 因此，DFS 返回 1，正确反映了在 XOR 约束下没有一对可以安全共存，因为每个 XOR 都会生成与至少一个操作数相当的值。
