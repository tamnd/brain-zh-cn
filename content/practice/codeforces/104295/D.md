 ## 解决方案
 ## 问题理解

 我们得到了一组固定的现有姓氏，每个姓氏都写成一串小写字母和连字符。 然后我们会得到几个新生儿的候选名字。 对于每个候选人，我们必须决定它是否可以接受。 

候选人在两种情况下被拒绝。 首先，如果它已经存在于现有名称中，则不能重复使用。 其次，即使它是新的，如果它“像”任何现有名称一样结尾，那么它仍然是无效的，在该语句所描述的意义上：我们查看后缀结构，其中匹配忽略任意前缀，但尊重连字符分隔部分的内部结构。 实际上，这简化为检查一个名称在连字符上对齐时是否可以被视为另一个名称的后缀模式，这意味着片段的结束序列完全匹配。 

重新表述该条件的一个有用方法是，我们关心字符级别的后缀，但限制连字符是结构的一部分。 因此，如果我们能够以与定义一致的方式从两个字符串中去除一些前缀（可能为空），留下相同的剩余字符串，则两个名称在末尾被认为是匹配的。 

限制很大：最多 10,000 个现有名称和 10,000 个查询，每个查询的长度最多为 50。通过完整字符串检查将每个查询与每个存储的名称进行简单比较将需要最多 1 亿次比较，每个最多 50 个字符，这仍然是边界，但如果我们在每次检查时重复子字符串操作或重建字符串，就会变得有风险。 更重要的是，每对的简单后缀匹配可能会演变成重复扫描。 

关键的结构问题是我们不是比较任意子字符串，而是检查完整字符串及其后缀的成员资格。 这强烈建议采用预处理结构，例如完整字符串的哈希集和与有效“家庭结尾”相对应的所有后缀的另一组。 

当候选名称与现有名称完全相等时，就会出现微妙的边缘情况。 即使它也匹配其自己的后缀条件，也必须立即拒绝。 另一个边缘情况是两个名称共享相同的后缀但前缀不同，例如“anna-katerina-mymla”和“mymla”。 等于“mymla”的候选者无效，任何以“mymla”结尾的较长名称也无效。 

最后，名称相对较短（≤ 50），因此为每个名称生成所有后缀是可行的，但我们必须确保以受控方式生成它们，而不是在嵌套循环内重复切片字符串。 

## 方法

 蛮力方法很简单。 对于每个查询名称，我们将其与每个现有名称进行比较。 我们首先检查相等性，然后检查查询是否与现有名称的后缀条件匹配。 直接后缀检查需要从两个字符串的末尾进行扫描，可能在分隔符一致的剪切后对齐。 每次比较的成本为 O(L)，其中 L ≤ 50，因此总成本变为 O(nqL)，在最坏的情况下为 10,000 × 10,000 × 50，太大了。 

关键的观察结果是后缀无效仅取决于查询是否显示为任何现有名称的有效后缀模式。 我们可以预处理现有名称的所有后缀并将它们存储在哈希集中，而不是为每个查询重新计算。 然后，每个查询减少为两个常量时间检查：现有集合中的完整成员资格和后缀集合中的成员资格。 

我们通过迭代名称中的每个位置并获取从那里开始的子字符串来生成后缀。 由于名称很短，每个名称最多存在 50 个后缀，因此预处理总量约为 500,000 个子字符串，完全在限制范围内。 

这将问题转化为两个集合上的成员资格查询问题。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nqL) | O(1) | O(1) | 太慢了|
 | 最佳（名称和后缀的哈希集）| O((n + q)L) | O((n + q)L) | O(nL) | 已接受 |

 ## 算法演练

 我们维护两个哈希集，一个用于所有现有名称，另一个用于从它们派生的所有后缀。 

1. 读取所有现有名称并将每个全名插入到名为的集合中`names`。 这允许对拒绝进行恒定时间相等检查。 
2. 对于每个现有名称，通过从每个索引开始到末尾获取子字符串来生成所有后缀，并将每个后缀插入到名为`suffixes`。 这捕获了所有可能使候选无效的结束模式。 
3.对于每个查询名称，首先检查它是否存在于`names`。 如果是，则立即输出“Bad”，因为禁止重复。 
4. 否则，检查查询是否存在于`suffixes`。 如果是，则输出“Bad”，因为它与现有家庭成员的结束模式匹配。 
5. 如果两个条件都不成立，则输出“Good”。 

顺序很重要：必须首先检查相等性，因为相等性也意味着后缀成员资格，但代表更强的无效条件。 

### 为什么它有效

 后缀集包含可以作为某些现有名称的有效结尾出现的所有字符串。 任何无效候选者必须与现有名称相同或显示为这些后缀之一。 由于后缀生成会枚举所有可能的尾部子字符串，因此不会遗漏任何无效模式。 相反，后缀集中的任何字符串都对应于某个现有名称的实际后缀，因此将其标记为无效是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    names = set()
    suffixes = set()

    for _ in range(n):
        s = input().strip()
        names.add(s)
        L = len(s)
        for i in range(L):
            suffixes.add(s[i:])

    q = int(input())
    out = []

    for _ in range(q):
        t = input().strip()
        if t in names:
            out.append("Bad")
        elif t in suffixes:
            out.append("Bad")
        else:
            out.append("Good")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案使用两个集合来区分精确匹配和基于后缀的失效。 后缀生成循环是唯一需要大量预处理的部分，但它在所有输入的总字符串长度上保持线性。 每个查询都减少为两次哈希查找。 

一个微妙的点是我们直接存储原始后缀字符串。 由于最大字符串长度为 50，因此切片成本是有限的并且不会影响渐近性能。

 ## 边缘情况

 一种重要的情况是查询完全等于现有名称。 对于输入：```
1
mymla-my
1
mymla-my
```该算法将名称插入`names`，然后检查查询。 第一个条件`t in names`为 true，因此输出立即为“Bad”。 尽管它也在后缀集中，但早期的相等性检查正确地对其进行了分类。 

另一种情况是查询不是全名而是多个不同名称的后缀：```
2
a-b-c
x-b-c
1
b-c
```两个现有名称都会生成后缀“b-c”。 后缀集包含它一次，但这就足够了。 查询不在`names`，但它是在`suffixes`，所以被拒绝。 这表明不同来源之间的重复并不重要，因为集合会自动折叠它们。
