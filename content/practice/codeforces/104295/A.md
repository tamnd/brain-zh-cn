 ## 解决方案
 ## 问题理解

 该问题描述了一个行为类似于时钟的圆形蛋糕。 首先在中午切蛋糕，然后一系列人在 12 点到 24 点之间的固定整数时间到达。每个到达的人都在该时间创建一个切块，并且蛋糕在连续切块之间被分成多个部分。 每个人只拿一块蛋糕，如果多个人在同一时间到达，他们平分这块蛋糕。 

我们得到两个固定人的到达时间：父亲在时间 p 和母亲在时间 m。 主角可以选择一个小时 x 进行第一次切割。 之后，p 和 m 处的切割将自动发生，将蛋糕分成圆上的三个相关弧线。 

由于蛋糕在 12 小时的周期内呈圆形，因此有趣的结构是切割点之间的顺时针距离以 12 小时为模。 主角想要选择 x，使得包含 x 的片段（他在其他人进一步雕刻之前，在切割后立即得到的部分）尽可能大。 如果多个 x 给出相同的最大段大小，我们必须选择最早的这样的时间。 

输入大小非常小，只有 12 到 24 之间的两个整数，因此恒定时间或微小的强力解决方案就足够了。 这立即排除了除了检查所有可能的候选人削减职位之外的任何事情，这些职位在周期中最多 12 个有意义的小时。 

当 p 和 m 相等时，会出现微妙的边缘情况。 在这种情况下，两次切割同时进行，并且该段在该时间实际上被分成两等份。 另一个边缘情况是最佳时段在午夜前后结束，例如循环时间中的 23 点到 12 点。 

## 方法

 天真的想法很简单。 尝试从 12 点到 24 点之间的每一个可能的小时 x 作为 Muumi 巨魔的切入位置。 对于x的每一个选择，我们模拟在12处切蛋糕，然后在x处，然后在p和m处切蛋糕，并根据顺时针遍历的规则计算属于主角的线段的大小。 

由于只需要切三刀，蛋糕就被有效地分割成 12 小时圆上的弧形。 对分割点以 12 为模进行排序后，我们计算所有连续的间隙，并根据 x 在排序中的位置确定哪个间隙对应于主角的棋子。 

这种蛮力方法在实践中是常数时间，因为最多有 13 个候选位置，并且每次模拟的时间复杂度为 O(1)。 然而，我们可以进一步简化。 

关键的观察是，主角的棋子始终是 {x, p, m, 12-start} 中从 x 到下一个切口的顺时针距离。 由于起始切点固定为12，因此我们只需要考虑圆上所有点对之间的距离。 x 的最佳选择始终是边界点之一或与其相邻的点，因为最佳线段出现在连续排序的切割点之间。 因此，我们只需要测试 x 等于 12、p、m 或它们在圆上的邻居，这就减少了检查所有 12 个可能的小时。 

最终的解决方案只是对所有候选 x 进行暴力破解并计算所得的段大小。

 ## 算法演练

1. 通过映射 12 → 0 并将其他时间保留为 (t - 12)，将所有时间转换为 12 小时周期上的位置。 这简化了循环算术并避免与 24 小时换行混淆。 
2. 对于[12, 24]中每一个可能的切割时间x，将其转换为循环形式并将其视为候选起始切割。 主角的棋子将是从 x 开始的顺时针线段，直到固定点之间的下一次切割。 
3. 对于每个候选 x，构建割点集 {0（初始割点）, x, p, m}，全部以 12 为模进行缩减。 
4. 将这些点在圆上顺时针排序。 计算连续点之间的距离，包括从最后一个点到第一个点的环绕距离。 
5. 确定从 x 开始的段。 这个片段的长度就是主角做出这个选择的收获。 
6. 跟踪所有 x 上的最大线段长度。 如果多个 x 产生相同的值，则按时间顺序保留最小的 x。 

关键的推理步骤是，一旦所有的切分都放置完毕，蛋糕就被完全分割成弧线，每个候选x简单地确定哪条弧线属于主角。 

### 为什么它有效

 问题的结构将一切简化为最多由三个切割引起的圆形分区。 关于到达顺序的任何额外推理都不会更改最终分区，只会更改哪个段属于谁的标签。 由于 x 是唯一可控的切割，因此其效果完全由其相对于圆上 p 和 m 的位置决定。 彻底评估所有布局可确保考虑最佳弧线。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def to_mod(t):
    return (t - 12) % 12

def solve():
    p, m = map(int, input().split())
    
    best_len = -1
    best_x = 10**9
    
    for x in range(12, 25):
        pts = [0, to_mod(p), to_mod(m), to_mod(x)]
        pts.sort()

        # compute circular gaps
        best_piece = 0
        for i in range(4):
            a = pts[i]
            b = pts[(i + 1) % 4]
            gap = (b - a) % 12
            
            # segment starting at x
            if a == to_mod(x):
                best_piece = gap
                break
        
        if best_piece > best_len or (best_piece == best_len and x < best_x):
            best_len = best_piece
            best_x = x
    
    print(best_x)

if __name__ == "__main__":
    solve()
```实现直接遵循循环分区模型。 功能`to_mod`将时间标准化为 0 到 11 范围，这简化了环绕算术。 

对于每个候选切割时间 x，我们将其与 p、m 以及 12 处的初始切割（映射到 0）一起插入到切割集合中。 对这些进行排序给出了顺时针顺序。 然后，循环找到从 x 开始的线段，并计算其长度作为与下一次切割的差值，模 12。 

比较逻辑确保我们始终存储达到最大分段的最早时间。

 ## 边缘情况

 当 p 等于 m 时，两条切口在圆上重合。 该算法仍然插入重复点，但排序和间隙计算自然会产生一个零长度段和一个完整段，这正确地反映了结构。 所选择的 x 就是达到最大弧度的最早时间。 

当切割发生在环绕附近时，例如 p = 23 和 m = 24，模转换会将它们放在圆上相邻的位置。 使用模算术正确计算从 11 到 0 的换行间隙，确保不会丢失任何段。 

当 x 与 p 或 m 重合时，重复点会出现在排序列表中。 间隙计算仍然为重复项分配零长度段，并且算法仍然识别来自 x 的正确传出弧，因为它显式选择从 x 开始的边。
