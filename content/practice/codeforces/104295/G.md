 ## 解决方案
 ## 问题理解

 我们得到了塔高度的集合。 有$n$塔，哪里$n$保证是奇数，并且每个塔都有一些初始高度。 我们还被赋予$k$额外的单位立方体。 每个立方体都可以添加到一个塔中，使其高度增加一倍。 

当我们分发完所有内容后$k$以我们喜欢的任何方式排列立方体，最终配置按非降序排序。 我们对排序后的完整数组不感兴趣，只对中值元素感兴趣，这意味着$\frac{n+1}{2}$-最小的高度。 我们的目标是选择如何分配$k$立方体，使这个中值尽可能大。 

关键的张力在于，向一个塔添加立方体可能会也可能不会影响中位数，具体取决于排序后该塔最终是否低于或高于中位数位置。 由于排序是在最后应用的，因此塔的身份并不重要，重要的是它们最终的多重值集。 

限制条件很大：$n$最多可达 300,000 并且$k$最多$10^9$，因此任何增量模拟立方体放置或重复排序的解决方案都是立即不可能的。 排序一次就可以了，但是任何尝试动态地重复调整和重新评估中位数的行为都会失败。 

出现微妙的边缘情况时$k = 0$。 然后我们简单地返回原始数组的中位数，但即使在这种微不足道的情况下，推理也必须与一般方法保持一致。 

另一个重要的边缘情况是当中值​​边界周围许多值相等时。 天真的直觉可能会尝试“直接提升中间塔”，但由于排序发生在所有操作之后，因此增加一个元素可能只会将其推到其他元素之上，而不会真正改善中间位置，除非提升了足够的元素。 

## 方法

 蛮力方法会尝试分配$k$以所有可能的方式计算立方体，然后计算排序后得到的中位数。 即使我们通过考虑每个增量的方式来进行离散化$n$塔，这相当于分布$k$相同的项目放入$n$桶，其中有$\binom{k+n-1}{n-1}$的可能性。 即使对于很小的值，这也会带来天文数字的增长，并且是完全不可行的。 

一个稍微结构化的蛮力想法是尝试贪婪分配：反复向塔中添加一个立方体，该立方体目前看来对增加中位数最有利。 问题在于中位数取决于全局排序，因此局部贪婪选择无法可靠地跟踪未来变化后哪个元素将最终位于中位数位置。 

关键的观察是停止跟踪单个塔，而是关注阈值。 假设我们猜测一个目标高度$x$为中位数。 问题是：我们能否确保至少一半的塔最终的高度至少$x$？ 如果我们可以的话$x$排序后可以得到中值。 

为了使此检查有效，我们注意到每个初始高度低于$x$需要至少提高到$x$，并且每个这样的塔都有明确定义的立方体成本。 塔楼已达到或高于$x$自然有助于在不花费立方体的情况下满足中值条件。 

这将问题转化为决定阈值有多大$x$我们可以用有限的预算提供支持$k$增量。 由于可行性是单调的$x$，我们可以二分查找答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分布 | 指数| O(n) | 太慢了|
 | 贪心/直接模拟 | O(k log n) | O(k log n) | O(n) | 太慢了|
 | 二分查找+可行性检查 | O(n log maxA) | O(n log maxA) | O(n) | 已接受 |

 ## 算法演练

 我们对数组进行排序，以便对排名的推理变得稳定。 设目标中位位置为$mid = \frac{n}{2}$以 0 索引项表示。 

然后我们对答案进行二分查找$x$，检查我们是否可以至少使中位数$x$。 

1. 对高度数组进行排序。 需要进行排序，以便我们可以推断有多少元素低于或高于阈值，而无需跟踪身份。 
2. 定义函数`can(x)`这决定了中位数是否可能至少为$x$。 
3. 内部`can(x)`，我们迭代所有塔并计算需要多少个立方体来升高每个高度小于$x$最多$x$。 对于每个这样的塔的高度$a[i] < x$，我们积累$x - a[i]$。 
4. 如果总成本超过$k$，我们立即返回 false。 这是因为即使在考虑最佳分布之前，我们也已经无法提升足够的质量来确保中值阈值。 
5. 如果总成本在$k$，我们返回true，这意味着我们可以迫使至少一半的塔达到高度$x$或更高，这保证了中值条件。 
6.我们二分查找$x$在从最小可能高度到最大可能高度的范围内$k$，因为中位数不能超过所有立方体都放置在相关塔上的情况。 
7.最终答案是最大的$x$为此`can(x)`是真的。 

### 为什么它有效

 正确性取决于中值条件仅取决于有多少元素至少为某个值，而不取决于它们的身份。 一旦我们确定了候选人$x$, 以下任何塔$x$如果我们希望它对上半部分有贡献，则必须增加才能达到它。 在上面已经有的塔上花费立方体$x$对于可行性来说从来都不是必需的$x$，因为它们已经满足约束条件。 

这创建了一个单调的可行性结构：如果我们至少可以实现中位数$x$，那么我们也可以实现任意$y < x$，因为所需的成本只会随着阈值的降低而降低。 这种单调性正是二分查找有效的原因。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))
a.sort()

mid = n // 2

def can(x):
    need = 0
    for i in range(n):
        if a[i] < x:
            need += x - a[i]
            if need > k:
                return False
    return True

lo, hi = min(a), max(a) + k

while lo < hi:
    mid_val = (lo + hi + 1) // 2
    if can(mid_val):
        lo = mid_val
    else:
        hi = mid_val - 1

print(lo)
```实现首先对数组进行排序，以便我们可以按顺序处理高度，尽管可行性检查本身并不依赖于排序后的位置更新。 

这`can(x)`函数计算提升下面每个元素所需的立方体总数$x$最多$x$。 提前退出时`need > k`对于效率至关重要，尤其是当$k$很大。 

二分搜索使用中上偏差`(lo + hi + 1) // 2`以避免向上收敛时无限循环。 搜索空间的安全边界为`max(a) + k`因为将所有立方体放在一个塔上最多可以增加任何元素$k$。 

## 工作示例

 ### 示例 1

 输入：```
5 0
1 3 2 5 2
```排序数组：`[1, 2, 2, 3, 5]`，中位索引为 2（0 索引）。 

我们测试可行性：

 | x| 达到 x 的成本 | 可以(x)|
 | --- | --- | --- |
 | 2 | (1→2)=1 | (1→2)=1 | 是的 |
 | 3 | (1→3)=2 + (2→3)=1 + (2→3)=1 = 4 | 没有|

 最大可行值为 2。 

这表明，如果没有额外的立方体，我们就无法推动足够的质量来将中位数提高到超过其初始值。 

### 示例 2

 输入：```
5 3
1 5 2 2 3
```排序：`[1, 2, 2, 3, 5]`我们尝试提高阈值：

 | x| 成本| 可行|
 | --- | --- | --- |
 | 3 | (1→3)=2 + (2→3)=1 + (2→3)=1 = 4 | 没有|
 | 2 | (1→2)=1 | (1→2)=1 | 是的 |

 所以即使分配了 3 个立方体，答案仍然是 2。 

这表明，提高中位数需要足够的预算来同时提升多个要素，而不仅仅是一个。

import sys, io

def run(inp: str) -> str:

    import sys
    input = sys.stdin.readline

    a = list(map(int, input().split()))

        need = 0
        for v in a:
            if v < x:
                need += x - v

        else:

 ## 边缘情况

 对于$n = 1$，中位数是唯一的元素，因此每个立方体都直接增加答案。 该算法处理这个问题是因为可行性检查只是累积$k$变成单个值并且二分查找达到$a[0] + k$。 

当所有元素都相同时，只有存在足够多的立方体以将其中至少一半提高到阈值以上，中位数才会增加。 可行性函数正确地反映了这一点，因为它为以下每个元素收取成本$x$，确保仅提升一个元素是远远不够的。 

什么时候$k = 0$，二分查找折叠到原来的中位数。 由于没有值$x$高于中位数是可行的，搜索自然返回排序后的中间元素，无需特殊大小写。
