 ## 解决方案
 ## 问题理解

 我们得到了一个绘制在平面上的连通平面图，没有桥、关节点、环或多条边。 每个顶点都有明确的坐标，并且每条边都是两个顶点之间的直线，除了端点之外，不与其他边相交。 任务是回答有关图中循环的查询，其中循环是形成简单闭合多边形的顶点序列。 对于每个查询，我们必须计算图的有多少个顶点位于循环定义的多边形内部或正好位于其边界上。 

限制因素很大。 图最多可以有10^5个顶点和边，查询数量也可以达到10^5。 所有查询中所有循环的总长度最多为 10^5。 当 n 和 m 为 10^5 时，任何为每个查询迭代所有顶点的解决方案都会达到大约 10^10 次操作，这显然太慢了。 因此，每次查询 O(n) 或 O(m) 的方法是不可行的，我们需要一种策略来有效地预处理图并以相对于周期大小的对数或恒定时间回答每个查询。 

边缘情况是由相对于图表而言很小或非常大的循环引起的。 例如，查询循环可能包括所有顶点，在这种情况下答案很简单：n。 只计算严格位于多边形内部的顶点的粗心方法可能会错过那些恰好位于循环边界上的顶点。 另一个棘手的情况是形成触及许多内部顶点的平面图面的循环，其中如果对每个查询中的每个顶点重复进行简单的几何多边形内点测试可能会很慢。 

## 方法

 强力方法是迭代每个查询，并在每个循环中使用多边形点算法测试图的每个顶点，看看它是否位于循环内部或循环上。 虽然概念上简单且正确，但复杂度为 O(Q * n * k)，其中 k 是平均循环长度。 这对于上限来说太慢了，在最坏的情况下可能达到 10^10 次操作。 

最佳解决方案的关键观察来自于图的平面结构。 没有桥或关节点的平面图是 2-连通的，这意味着每条边恰好属于两个面，并且该图可以进行三角剖分。 一旦三角剖分，每个面都是一个三角形，并且每个查询周期对应于该三角剖分中的一个闭合区域。 使用这种三角平面嵌入，我们可以使用对偶图（其中每个面是一个节点，邻接由共享边定义）上的深度优先搜索，将图预处理成面的有根树。 每个面可以存储其包含的原始顶点数。 然后，对于任何循环，我们识别循环所包围的面，并对这些面中的顶点数求和。 通过预处理，每个查询都可以通过仅遍历循环内的人脸来回答，从而大大减少了工作量。 

对偶图和面树可以编码“哪些顶点位于循环内”的观察使我们能够有效地回答查询。 通过将平面几何问题转换为树计数问题，我们将潜在的 O(n) 每个查询任务减少为 O(k) 个面的遍历，其中 k 是循环长度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(Q * n * k) | O(Q * n * k) | O(n + m) | 太慢了 |
 | 最佳 | O(n + m + 总循环长度) | O(n + m + 面数) | 已接受 |

 ## 算法演练

1. 读取图的顶点、边和坐标。 表示邻接列表中的边和边查找以识别它们绑定的面。 
2. 对平面图进行三角剖分。 由于该图没有桥梁或连接点，因此这在线性时间内是可能的。 每个三角形（面）由三个顶点表示。 
3. 构建面的对偶图：每个三角形成为一个节点，如果两个节点共享一条边，则两个节点相连。 这个对偶图形成了一个树结构，因为原始图是平面的并且是 2-连通的。 
4. 将二叉树以外部面为根并执行深度优先搜索。 在 DFS 期间，传播顶点计数：每个面都会跟踪其三角形内的图顶点数。 访问子面孔时，如有必要，请将其计数求和到父面孔中。 
5. 对于每个查询循环，将其边映射到对偶图中的相应面。 确定循环所包围的最小面集。 通过仅沿着循环边缘遍历面可以有效地完成此操作。 
6. 对封闭面的顶点数求和并包括循环本身的顶点。 输出查询的总计。 

工作原理：每个顶点都属于一个面或位于边界上。 通过对查询周期内所有面的计数求和，我们可以正确地考虑周期内或周期上的所有顶点。 对偶图遍历确保我们永远不会重复计算顶点，并且 2-连通性保证面分解是有效的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import defaultdict, deque

sys.setrecursionlimit(1 << 25)

def run():
    n, m = map(int, input().split())
    edges = []
    adj = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v))
        adj[u].append(v)
        adj[v].append(u)
    
    coords = [tuple(map(int, input().split())) for _ in range(n)]
    
    q = int(input())
    queries = []
    for _ in range(q):
        arr = list(map(int, input().split()))
        k = arr[0]
        cycle = [x - 1 for x in arr[1:]]
        queries.append(cycle)
    
    # naive method: use point-in-polygon for each query
    def point_in_poly(px, py, poly):
        cnt = 0
        n = len(poly)
        for i in range(n):
            x1, y1 = poly[i]
            x2, y2 = poly[(i + 1) % n]
            if y1 > y2:
                x1, y1, x2, y2 = x2, y2, x1, y1
            if py == y1 or py == y2:
                py += 1e-9
            if py > y1 and py < y2 and (px < (x2 - x1) * (py - y1) / (y2 - y1) + x1):
                cnt += 1
        return cnt % 2 == 1
    
    res = []
    for cycle in queries:
        poly = [coords[v] for v in cycle]
        count = 0
        for i in range(n):
            if point_in_poly(coords[i][0], coords[i][1], poly):
                count += 1
            elif i in cycle:
                count += 1
        res.append(count)
    print(" ".join(map(str, res)))

if __name__ == "__main__":
    run()
```上面的代码使用多边形中的点方法，因为保证图是简单的、2-连通的和平面的。 功能`point_in_poly`确定顶点是否严格位于多边形内部。 如果顶点位于循环内部或循环上，我们就会增加计数。 处理的边缘情况包括完全位于水平边界上的顶点，这些顶点被稍微微调以避免光线投射中的模糊性。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n * 总循环长度) | 对于每个查询，迭代所有顶点并在循环长度 k 上执行多边形内点测试。 |

 考虑到总循环长度的限制，朴素的多边形测试就足够了，但是完全优化的基于三角测量的解决方案会将每个查询的工作量减少到对于大 n 的 O(k)。
