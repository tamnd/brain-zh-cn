 ## 解决方案
 ## 问题理解

 我们得到一个仅由四个括号字符组成的字符串：`(`,`)`,`[`和`]`。 弦不一定是平衡的。 

在这个字符串的所有子串中，我们需要找到一个构成正确括号序列的子串。 正确的括号序列必须满足通常的嵌套规则，这意味着每个左括号都与相同类型的右括号匹配，并且括号对正确嵌套。 

目标不是最大化子串的长度。 相反，我们想要包含最多数量的左方括号的有效子字符串`'['`。 找到这样的子串后，我们必须输出`'['`其中的字符和子字符串本身。 

字符串长度可以达到$10^5$。 二次算法需要粗略地检查$10^{10}$子串，这是完全不可行的。 甚至一个$O(n^2)$验证策略远远超出了时间限制。 解决方案必须接近线性时间。 

一些边缘情况使问题比普通的括号匹配更加棘手。 

考虑：```
([)]
```该子字符串跨越平衡的括号数量，但它不是正确的括号序列，因为嵌套顺序错误。 任何仅基于计算括号类型的解决方案都会错误地接受它。 

考虑：```
][
```不存在非空的正确子串。 答案一定是：```
0
```第二行为空。 粗心的实现可能会尝试输出其中一个字符。 

考虑：```
[]()[]
```整个字符串有效，包含两个`'['`人物。 如果我们只搜索最长的有效子串，我们仍然会成功，但一般来说，最佳值是由子串的数量决定的。`'['`，而不是长度。 

考虑：```
([[]])
```整个字符串有效并包含两个左方括号。 解决方案必须正确计算嵌套结构内的方括号，而不仅仅是在顶层。 

## 方法

 蛮力的想法很简单。 枚举每个子串，检查它是否是正确的括号序列，统计有多少个`'['`包含的字符，并保留最好的一个。 

正确性是立即的，因为每个候选子串都会被检查。 问题是成本。 有$O(n^2)$子串。 即使有效性检查只需要$O(n)$，总复杂度变为$O(n^3)$。 和$n = 10^5$，这是没有希望的。 

关键的观察是我们不需要独立验证每个子字符串。 

使用标准堆栈过程可以识别正确的括号序列。 从左到右扫描字符串时，每个右括号要么匹配当前堆栈顶部，要么破坏穿过该位置的任何子字符串的有效性。 

这与经典的“最长有效括号”问题非常相似。 我们可以维护一堆左括号及其位置。 每当找到匹配对时，我们就获得以当前位置结束的有效段。 通过跟踪使段无效的最近位置，我们可以确定以每个索引结尾的最大有效子串。 

剩下的要求是最大化`'['`人物。 这可以通过前缀和数组来处理。 一旦我们知道了有效子串的边界，就可以在常数时间内获得其中的左方括号的数量。 

该堆栈在线性时间内识别所有最大有效段，并且前缀和允许对每个候选者进行有效评分。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 构建一个前缀和数组，其中`pref[i]`存储的数量`'['`第一个中的字符`i`人物。 

这允许在恒定时间内对任何子字符串内的左方括号进行计数。 
2. 维护一个包含对的堆栈`(position, bracket)`用于无与伦比的左括号。 
3.维护数组`dp`在哪里`dp[i]`表示正好在位置结束的最长正确括号序列的长度`i`。 
4. 从左到右扫描字符串。 
5. 当遇到左括号时，将其位置和类型推入堆栈。 
6. 当遇到右括号时，检查堆栈顶部是否包含匹配的左括号。 

如果没有，则清除堆栈。 任何未来的有效子串都不能跨越这个不匹配的位置。 
7. 如果存在匹配，则弹出左括号位置`j`。 
8. 一对`(j, i)`形成一个有效的块。 放：```
dp[i] = i - j + 1
```9. 如果有一个有效的块紧接在之前结束`j`，延伸通过它：```
dp[i] += dp[j - 1]
```这会将相邻的有效片段合并为一个更大的有效子字符串。 
10. 结束于的有效子字符串`i`已离开边界：```
L = i - dp[i] + 1
```11. 使用前缀和计算该子字符串内的左方括号：```
count = pref[i + 1] - pref[L]
```12. 如果该计数大于目前找到的最佳答案，则存储子串边界。 
13.处理完所有位置后，输出最佳计数和对应的子串。 

### 为什么它有效

 堆栈保证每个匹配对都遵循正确括号序列的嵌套规则。 每当发生不匹配时，所有部分构造的序列都无法跨越该位置，因此清除堆栈是正确的。 

对于每个在位置成功匹配左括号的右括号`j`，该段来自`j`到当前位置有效。 如果另一个有效段紧接之前结束`j`，连接两个段仍然有效，这正是`dp`扩展步骤捕获。 

因此`dp[i]`始终等于以位置结束的最长有效括号子串的长度`i`。 每个最大有效子字符串都显示为这些候选字符串之一。 由于前缀和计算了`'['`当每个候选字符中的字符准确无误时，算法会检查所有相关的有效子字符串并选择得分最高的子字符串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    pref = [0] * (n + 1)
    for i, ch in enumerate(s):
        pref[i + 1] = pref[i] + (1 if ch == '[' else 0)

    dp = [0] * n
    stack = []

    best_count = 0
    best_l = 0
    best_r = -1

    match = {
        ')': '(',
        ']': '['
    }

    for i, ch in enumerate(s):
        if ch in '([':
            stack.append((i, ch))
        else:
            if stack and stack[-1][1] == match[ch]:
                j, _ = stack.pop()

                dp[i] = i - j + 1
                if j > 0:
                    dp[i] += dp[j - 1]

                l = i - dp[i] + 1
                cnt = pref[i + 1] - pref[l]

                if cnt > best_count:
                    best_count = cnt
                    best_l = l
                    best_r = i
            else:
                stack.clear()

    print(best_count)
    if best_r >= best_l:
        print(s[best_l:best_r + 1])
    else:
        print()

if __name__ == "__main__":
    solve()
```前缀和部分允许对任何区间内的左方括号进行恒定时间计数。 如果没有它，我们将需要再次扫描每个候选子串，从而增加了复杂性。 

堆栈存储括号类型及其位置。 该位置是必需的，因为一旦找到匹配项，我们就需要新形成的有效块的确切开始位置。 

这`dp`数组与经典的有效括号问题中使用的想法相同。 当一对在位置之间匹配时`j`和`i`，段长度最初为`i - j + 1`。 如果另一个有效序列结束于`j - 1`，两个线段相邻并且可以合并，所以我们添加`dp[j - 1]`。 

左边界根据长度重建：```
left = i - dp[i] + 1
```这避免了为每个状态显式存储边界。 

一个微妙的点是清除不匹配的堆栈。 在堆栈中留下不匹配的左括号将允许将来的匹配跨越无效位置，从而产生实际上不是正确括号序列的子字符串。

 ## 边缘情况

 考虑：```
([)]
```加工达到`)`而栈顶是`'['`。 括号不匹配，因此堆栈被清除。 未来的子串不能跨越该位置。 每一个`dp`值保持为零，并且答案正确地报告为零。 

考虑：```
][
```第一个字符是右括号，没有匹配的开括号。 堆栈为空并保持为空。 第二个字符只是被推送但从未匹配。 没有发现有效的子字符串，因此输出为：```
0
```考虑：```
()()
```整个字符串是正确的括号序列，但不包含左方括号。 最佳计数保持为零。 在这种情况下，官方解决方案也会输出一个空字符串，因为没有有效的子字符串具有严格的正分数。 该算法自然会产生这种行为。 

考虑：```
([[]])
```匹配按顺序发生`[ ]`,`[ ]`， 然后`( )`。 每个成功的匹配都会扩展较早的有效块`dp[j - 1]`过渡。 最终的有效子字符串成为整个字符串，并且前缀和正确地计算了两个左方括号。
