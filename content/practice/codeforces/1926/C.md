 ## 解决方案
 ## 问题理解

 对于每个测试用例，我们都会得到一个数字`n`。 Vlad 写入所有整数`1`通过`n`在黑板上。 然后每个整数被其十进制数字之和替换。 

任务是计算$$\sum_{i=1}^{n} \text{digitSum}(i)$$在哪里`digitSum(i)`是数字的总和`i`。 

例如，当`n = 12`，数字和为：$$1,2,3,4,5,6,7,8,9,1,2,3$$他们的总数是`51`。 

约束是关键的观察结果。 最多可以有`10^4`测试用例，以及每个`n`可以大到`200000`。 通过迭代独立计算每个测试用例的答案`1`到`n`会多次重复同样的工作。 虽然`200000`本身并不大，这样做是为了`10000`测试用例将需要大约 20 亿次操作，这远远超出了适合的范围`0.5`第二时间限制。 

的最大值`n`只是`200000`，这表明了不同的策略。 由于每个查询都要求相同数字范围内的前缀和，因此我们可以预处理以下所有值的答案`1`到`200000`一次，然后在恒定时间内回答每个测试用例。 

一些边缘情况值得关注。 

考虑`n = 1`。 

输入：```
1
1
```答案是：```
1
```前缀数组必须正确初始化，以便第一个值不会被跳过。 

考虑`n = 10`。 

各数字之和为：$$1+2+3+4+5+6+7+8+9+1 = 46$$一个常见的错误是忘记了`digitSum(10) = 1`， 不是`10`。 

考虑`n = 99999`和`n = 100000`。 

当跨越 10 的幂时，数字和急剧下降：$$digitSum(99999)=45,\qquad digitSum(100000)=1$$任何在没有正确处理进位的情况下使用简单算术模式导出值的尝试都将在此类边界附近失败。 

## 方法

 最直接的解决方案是独立处理每个测试用例。 对于给定的`n`，迭代所有数字`1`到`n`，计算每位数字的和，并将结果累加。 

这是可行的，因为答案正是该范围内所有数字总和的总和。 问题是成本。 计算数字和大约需要`O(log n)`操作，我们必须对每个数字进行操作，直到`n`。 对于一个测试用例，复杂度大致为`O(n log n)`。 和`n = 200000`和`10000`测试用例时，工作量变得巨大。 

关键的观察是每个测试用例都要求相同类型的前缀查询：$$\text{answer}(n)=\sum_{i=1}^{n}\text{digitSum}(i)$$我们可以构建一次，而不是重复重新计算这些总和。 

让$$dp[i] = \text{digitSum}(i)$$和$$pref[i] = \sum_{j=1}^{i} dp[j]$$那么任何测试用例的答案都很简单`pref[n]`。 

由于最大可能`n`只是`200000`，我们可以在读取查询之前预先计算达到该限制的所有数字和和所有前缀和。 

还有另一个有用的观察。 一个数的数字和可以递归计算：$$digitSum(i)=digitSum(i//10)+(i\bmod 10)$$这允许所有数字和`1`到`200000`在线性时间内有效地计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每个测试用例的 O(n log n) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(MAXN) 预处理 + O(1) 每个查询 | O(最大N) | 已接受 |

 ## 算法演练

 1. 读取所有测试用例并存储它们的值。 
2. 求出预处理所需的最大可能值。 在这个问题中总是`200000`，但使用最大的查询值也可以。 
3. 创建数组`digit`在哪里`digit[i]`存储数字的总和`i`。 
4. 使用递归计算数字和$$digit[i] = digit[i // 10] + (i \% 10)$$最后一位数字贡献`i % 10`，其余数字正好是`i // 10`。 
5. 创建前缀和数组`pref`。 
6. 对于每个`i`, 计算$$pref[i] = pref[i-1] + digit[i]$$这一步之后，`pref[i]`等于所需的答案`i`。 
7. 对于每个测试用例，输出`pref[n]`。 

### 为什么它有效

 复发为`digit[i]`是正确的，因为每个十进制数都由其最后一位数字加上所有前面的数字组成。 将一个数拆分为`i // 10`和`i % 10`准确地将这两部分分开。 

前缀数组在处理索引后保持不变`i`,$$pref[i]=\sum_{k=1}^{i} digit[k]$$这最初是正确的`i=0`，每一步都精确地添加一个新的数字和。 最后`pref[n]`等于数字和的总和`1`通过`n`，这正是问题所需的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    queries = [int(input()) for _ in range(t)]

    mx = max(queries)

    digit = [0] * (mx + 1)
    pref = [0] * (mx + 1)

    for i in range(1, mx + 1):
        digit[i] = digit[i // 10] + (i % 10)
        pref[i] = pref[i - 1] + digit[i]

    out = [str(pref[n]) for n in queries]
    sys.stdout.write("\n".join(out))

solve()
```第一步读取每个查询，以便我们知道预处理必须进行到什么程度。 没有理由构建最多`200000`如果所有查询都较小。 

这`digit`数组使用递归```
digit[i] = digit[i // 10] + (i % 10)
```因为`i // 10`总是小于`i`，所需的值已经计算出来。 

前缀数组同时构建。 计算数字和后`i`，我们立即延长运行总计。 

Python 整数就足够了，因为最大的答案只有几百万。 不需要对溢出进行特殊处理。 

一个常见的实现错误是在以下位置开始循环`0`。 递归在那里也有效，但是前缀定义在以下情况下更清晰：`pref[0] = 0`处理开始于`1`。

 ## 边缘情况

 考虑尽可能最小的输入：```
1
1
```预处理循环计算：```
digit[1] = digit[0] + 1 = 1
pref[1] = pref[0] + 1 = 1
```算法输出`pref[1] = 1`，这是正确的。 

考虑第一个进位边界：```
1
10
```计算值是：```
digit[9] = 9
digit[10] = digit[1] + 0 = 1
```前缀和变为：```
45 + 1 = 46
```答案是正确的，因为`10`是`1`， 不是`10`。 

考虑一个长进位链：```
1
100000
```递归给出：```
digit[100000]
= digit[10000] + 0
= digit[1000] + 0
= digit[100] + 0
= digit[10] + 0
= digit[1] + 0
= 1
```该算法自然地处理这个问题，没有任何特殊情况。 前缀和已包含所有先前数字的贡献，因此添加此最终值会产生正确的结果。
