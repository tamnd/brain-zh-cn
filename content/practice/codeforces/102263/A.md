[CF 102263A - 容易吗？](https://codeforces.com/problemset/problem/102263/A)

 ## 解决方案
 ## 问题理解

 每个参赛团队都需要一份问题陈述的打印副本。 如果打印一份需要费用`k`硬币，有`n`团队，总成本为一份成本乘以团队数量。 

输入包含两个整数，`n`和`k`。 价值`n`告诉我们有多少团队需要副本，同时`k`是打印一份的价格。 所需的输出是为每个团队打印一份副本所需的硬币总数，这很简单`n * k`。 

这两个值都在 1 到 1000 之间。这些界限非常小，因此即使是线性算法也会立即完成。 不需要数组、图形、动态编程或任何迭代过程。 由于总数是直接从两个输入值获得的，因此恒定时间是自然的解决方案。 

最小可能的输入是`1 1`，这会产生`1`。 假设有多个团队的粗心实现可能会错误地处理这种情况，但从数学上讲，单个团队没有什么特别的。 

例如，使用输入`1 7`，只需要一份副本，因此输出为`7`。 由于不正确的循环边界而意外再次添加价格的实现可能会产生`14`。 

最大可能值也很简单。 有输入`1000 1000`，答案是`1000000`。 结果大于任一输入，因此在具有固定宽度整数类型的语言中使用不必要的窄整数类型的实现可能会在此问题的不同版本中溢出。 Python 整数不存在这个问题。 

## 方法

 直接的暴力方法可以模拟打印过程。 从总数为零开始并重复`n`次，添加`k`每次迭代的总数。 这是正确的，因为每次迭代都代表一个团队收到一份打印副本，因此在所有迭代之后，累积值正是所有副本的成本。 

在实际限制下，这种蛮力方法最多执行 1000 次加法。 一点也不慢，很容易被接受。 这里没有诚实的输入大小，在这种情况下，这种特殊的暴力方法会成为一个实际问题。 

更好的观察是重复添加相同的值`k`， 确切地`n`次，是乘法的定义。 而不是表演`k + k + ... + k`通过循环，我们可以计算`n * k`直接地。 这将工作量从成比例减少到`n`到固定数量的算术运算。 

蛮力之所以有效，是因为每个团队都做出了准确的贡献`k`硬币，但它为每个团队分别执行相同的计算。 问题的结构告诉我们，每个贡献都是相等的，因此整个总和可以分解为一个乘法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 接受这些限制 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取两个整数`n`和`k`。 第一个代表团队数量，第二个代表一份印刷成本。 
2. 计算`n * k`。 每个`n`团队需要一份副本，并且每份副本的费用都是准确的`k`，因此乘法给出了完整的成本，而无需明确模拟各个团队。 
3. 打印结果值。 不需要额外的处理，因为乘法已经代表了请求的总数。 

### 为什么它有效

 对于每支球队，评委们的花费都是准确的`k`硬币。 和`n`团队的总和可以写成重复总和`k + k + ... + k`，包含`n`条款。 根据乘法的定义，这个和等于`n * k`。 该算法精确地计算出该值，因此打印的结果就是所需的总成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
print(n * k)
```一线进口`sys`，允许使用该解决方案`sys.stdin.readline`根据竞争性编程输入的要求。 

第二行读取唯一的输入行并将其两个空格分隔的值转换为整数。 无需处理多个测试用例，因为问题恰好包含一对值。 

最后一行执行完整的计算并打印它。 没有循环边界或索引操作，因此不存在差一问题。 Python 的整数类型还可以安全地处理整个允许的结果。 

## 工作示例

 ### 示例 1

 用于输入`5 3`，有五个团队，每份印刷品需要三枚硬币。 

| n | k | 总计 |
 | ---| ---| ---|
 | 5 | 3 | 15 | 15

 乘法`5 * 3`给出`15`，所以评委需要15个硬币。 

### 示例 2

 用于输入`4 1`，有四支队伍，每个副本花费一枚硬币。 

| n | k | 总计 |
 | ---| ---| ---|
 | 4 | 1 | 4 |

 这里的乘法是`4 * 1`, 给予`4`。 这也演示了当一份副本的成本为最小可能值时的边界行为。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(1) | O(1) | 该解决方案执行一项乘法和一项输出运算。 |
 | 空间| O(1) | O(1) | 仅存储两个输入整数和结果。 |

 约束条件允许`n`和`k`最多为 1000，因此即使是模拟的 O(n) 方法也很容易足够快。 最优的 O(1) 解决方案更简单，并且完全消除了不必要的重复。 它的内存使用量也是恒定的。 

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline
    n, k = map(int, input().split())
    print(n * k)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# provided samples
assert run("5 3\n") == "15\n", "sample 1"
assert run("4 1\n") == "4\n", "sample 2"

# minimum-size input
assert run("1 1\n") == "1\n", "minimum values"

# maximum-size input
assert run("1000 1000\n") == "1000000\n", "maximum values"

# one team with a larger printing cost
assert run("1 1000\n") == "1000\n", "single team"

# minimum printing cost with the maximum number of teams
assert run("1000 1\n") == "1000\n", "unit cost"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 |`1 1`|`1`| 最小允许值 |
 |`1000 1000`|`1000000`| 最大值和乘法 |
 |`1 1000`|`1000`| 单队边界情况|
 |`1000 1`|`1000`| 多个团队的最低成本 |

 ## 边缘情况

 输入`1 1`是最小的有效情况。 算法读取`n = 1`和`k = 1`，计算`1 * 1`，并打印`1`。 不需要特殊情况，这比引入可能产生边界错误的条件更好。 

输入`1 7`代表一支球队以七枚硬币购买一份副本。 计算公式为`1 * 7 = 7`，所以输出是`7`。 基于循环的实现，其范围不正确，例如`range(1, n)`将执行零次并错误地产生零。 

输入`1000 1000`练习问题允许的最大值。 计算公式为`1000 * 1000 = 1000000`。 该算法不依赖于`n`由于其运算次数，Python 可以直接表示结果整数。 

输入`1000 1`测试另一个边界，其中每个副本的成本最低。 总计为`1000 * 1 = 1000`。 这证实了团队的数量，而不是单个副本的成本，决定了贡献总数的数量。
