 ## 解决方案
 ## 问题理解

 两名玩家从同一组牌开始，包含从 1 到 1 的所有整数`n`。 期间`n`回合中，每张牌都会被每个玩家使用一次，因为所选的牌会被移除。 两名玩家有效地产生纸牌的独立随机排列，然后轮流`i`比较卡片占据的位置`i`在这些排列中。 

每当 Ehab 的牌比 Zeyad 的牌大时，他就会获得积分。 如果 Ehab 上场`k`对抗较小的牌，他收到的正是`k`点。 相同的牌不得分。 

输入仅包含`n`， 和`1 <= n <= 10^6`。 大的上限排除了任何二次方`n`。 甚至一个`O(n^2)`计算需要`10^12`最大规模的迭代，远远超出了正常的竞争性编程时间限制所能支持的。 我们需要将整个游戏减少到恒定的算术量。 

第一个边缘情况是`n = 1`。 双方玩家都只有一张牌`1`，所以他们必须互相对抗并且没有人得分。 正确的输出是`0`。 

第二个边缘情况是一个小甲板，例如`n = 2`。 Ehab有卡`1`和`2`。 卡片`1`永远无法得分，而卡`2`与配对时得分准确`1`。 由于对手的牌与`2`同样可能是`1`或者`2`，其预期贡献为`2 * 1/2 = 1`。 因此正确答案是`1`。 一个粗心的解决方案假设每张牌总是与较小的牌相比得分，这会错误地计算`1 + 2 = 3`。 

第三个微妙的情况是平等。 当两个玩家选择相同的数字时，两个玩家都不会得分。 由于每张牌在每副牌中只出现一次，因此随机配对中的平等是可能的。 任何计算所有对手价值最多的公式`k`而不是严格小于`k`引入一个错误。 

## 方法

 直接方法可以分别计算每张 Ehab 卡的预期贡献。 为了一张卡`k`，我们可以检查所有`n`Zeyad 可能会打出的牌，确定是否`k`获胜，并平均所得分数。 为所有人做这件事`k`准确地要求`n^2`配对检查。 在`n = 10^6`， 那是`10^12`运算，因此即使计算在数学上是正确的，但它还是太慢了。 

通过单独查看一张牌，我们可以做得更好。 因为 Zeyad 的牌组是均匀随机排列，所以该牌与 Ehab 的牌配对`k`均匀分布在所有`n`牌。 正好有`k - 1`卡片小于`k`，和 Ehab 分数`k`正是当其中一张卡与他配对时。 

那么这张卡的概率`k`分数简直就是

 n k−1 ​ .

 因此，其预期贡献为

 k n k−1 ​ .

 期望的线性现在消除了推理不同回合之间依赖关系的需要。 即使涉及不同卡的事件不是独立的，我们也可以添加每张 Ehab 卡的预期贡献。 

总的期望是

 E= k=1 Σ n ​ k n k−1 ​ = n 1 ​ k=1 Σ n ​ (k 2 −k)。 

使用标准总和

 k=1 Σ n ​ k 2 = 6 n(n+1)(2n+1) ​

 和

 k=1 Σ n ​ k= 2 n(n+1) ​ ,

 我们得到

 E= n 1 ​ ( 6 n(n+1)(2n+1) ​ − 2 n(n+1) ​ )。 

因式分解和简化给出

 E= 3 n 2 −1 ​ 。 

因此，整个随机博弈可以用一个常数时间公式来代替。

 ## 算法演练

 1. 阅读`n`，它决定了两副牌中的完整牌组。 
2. 考虑任意 Ehab 卡`k`。 与它配对的对手的牌均匀分布在所有牌上`n`可能的卡片，因为两个随机排列是独立的。 
3. 数一下让 Ehab 得分的牌`k`。 确切地`k - 1`卡片的值小于`k`，所以这张卡得分的概率是`(k - 1) / n`。 
4. 将该概率乘以该卡得分时获得的分数。 预期贡献`k`是`k * (k - 1) / n`。 
5. 将每个贡献的总和`k`从`1`通过`n`。 通过期望的线性，我们可以添加期望的贡献，而不要求个体轮流是独立的。 
6. 将所得总和化简得到`(n² - 1) / 3`，然后将其打印为实数。 

### 为什么它有效

 对于每张固定卡`k`， 确切地`k - 1`对手的`n`卡片导致 Ehab 得分`k`点。 由于每张可能的对手牌都同样有可能与`k`，其预期贡献正是`k(k-1)/n`。 Ehab 牌组中的每张牌都只使用一次，因此总分是这些个人贡献的总和。 期望的线性保证了该总和等于期望的总分，无论配对之间存在任何依赖性。 代数将该总和简化为`(n² - 1)/3`，因此算法计算出精确的期望。 

## Python 解决方案```python
Pythonimport sysinput = sys.stdin.readline
n = int(input())
answer = (n * n - 1) / 3.0print(f"{answer:.10f}")
```输入仅包含一个整数，因此不需要额外的数据结构或重复的测试用例处理。 

表达式`n * n - 1`直接来自简化的期望。 Python 整数具有任意精度，因此即使在`n = 10^6`。 

划分由`3.0`产生适合所需输出容差的浮点结果。 在小数点后打印十位数字比所需的精度要高得多`10^-6`。 

减法必须在除法之前进行。 为了`n = 1`，表达式变为`(1 * 1 - 1) / 3 = 0`，正确处理尽可能小的甲板。

 ## 边缘情况

 对于`n = 1`，输入很简单`1`。 唯一可能的配对是卡`1`反对卡`1`。 由于相同的牌不计分，因此预期结果是`0`。 该公式产生`(1² - 1) / 3 = 0`，所以不需要特殊情况。 

为了`n = 2`，卡片是`1`和`2`。 卡片`1`有零张小牌，预期贡献为`0`。 卡片`2`在两个可能的对手中，有一个较小的对手，所以它的贡献是`2 * 1/2 = 1`。 最终的答案是`1`。 这会捕获意外地将平等视为胜利的实现。 

为了`n = 3`，贡献是`0`,`2/3`， 和`2`, 给予`8/3 = 2.6666666667`。 这会检查从整数到小数期望值的转换，并捕获较小卡片计数中的差一错误。 

为了`n = 10^6`，公式给出

 3 10 12 −1 ​ =333333333333。 

结果很大，但 Python 的任意精度整数可以准确地处理中间乘法。 即使在最大输入大小下也不需要循环、数组或模拟。
