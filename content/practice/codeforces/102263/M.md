 ## 解决方案
 ## 问题理解

 我们有一串小写字母。 我们可以自由交换任意两个位置，因此字符的顺序从来不是真正的限制。 第二个操作采用两个相等的相邻字母，并将它们替换为下一个字母。 例如，两个`c`角色可以合而为一`d`，同时两个`z`字符无法合并，因为后面没有字符`z`。 

目标是执行任意操作序列并获得字典顺序上最大的可能字符串。 由于可以进行任意交换，一旦我们知道每个字母还剩下多少个副本，我们就可以随时按降序排列它们。 因此，真正的问题是确定最佳的最终字母多重集。 

长度可以大到`10^5`。 这足以排除重复探索许多可能的操作序列或在每次操作后扫描整个字符串的算法。 线性或近线性解是合适的。 字母表只有 26 个字符，这为我们提供了一个特别有用的恒定大小维度，用于将信息从一个字母传递到下一个字母。 

在一些边缘情况下，粗心的实施可能会出错。 对于输入`aa`，正确的输出是`b`。 简单地对原始字符串进行排序会产生`aa`，缺少严格改进第一个字符的操作。 为了`zz`，正确的输出是`zz`， 因为`z`没有继任者。 盲目递增每一对的实现会错误地生成字母表之外的字符。 为了`yyy`，正确的输出是`zy`: 一对`y`变成`z`，而剩余的`y`不能参与其他操作。 最后，为了`aaaa`，答案是`c`， 不是`bb`。 前两次合并后我们得到`bb`，以及那两个`b`角色可以再次合并成`c`。 如果解决方案只处理每个字母一次而不向上携带新创建的字母对，那么就会错过这个级联。 

## 方法

 直接模拟可以重复搜索两个相等的字母，必要时交换字符以将这样的一对放在一起，用其后继者替换该对，并继续，直到没有有用的对为止。 如果最终处理每个可用的对，则这是正确的，因为每个操作都会将字符串长度减少一，并且交换允许任何两个相等的字符变得相邻。 

问题在于有效执行模拟的成本。 可以有多达`n - 1`运营。 例如，当字符串由 2 的幂数组成时，可以实现此最大值`a`人物。 和`n = 100000`，一个简单的实现，扫描当前字符串以在每个操作可以执行大约之后找到合并`100000 + 99999 + ... + 1 = 5,000,050,000`最坏情况下的字符检查。 探索不同可能的操作顺序更糟糕，因为它可以创建一个大的搜索树。 

关键的观察是掉期完全消除了头寸的重要性。 我们只需要每个字母的计数。 假设有`cnt[c]`一些信件的副本`c`。 每一对都可以替换为一个`c + 1`。 如果有`cnt[c] // 2`对，它们都可以转换，留下`cnt[c] % 2`的副本`c`并添加`cnt[c] // 2`复制到下一个字母。 

此操作始终有利于字典序最大化。 两份`c`被替换为严格较大字符的一份副本`c + 1`。 由于所有剩余字符都可以按降序排序，因此在字母表中向上移动一个字符可以得到这些字符的最大可能的领先贡献。 也没有理由保留较低字母处的对，因为它总是可以被转换，并且下一个字母处的任何新生成的对本身可以再次转换。 

这样整个过程就变成了一个小的进位操作。 我们处理字母表`a`通过`y`。 每个计数的奇偶校验保持在其当前字符，而计数的一半被传送到下一个字符。 这`z`计数永远不会改变，因为`zz`无法转换。 最后，我们输出每个剩余的字符`z`下降到`a`。 

暴力过程之所以有效，是因为每次合并都代表一次有效操作，但当合并数量变为线性并且每次合并都需要另一次扫描时，暴力过程就会失败。 只有字符计数才重要这一观察结果让我们可以用 25 个恒定时间计数转换来替换所有这些操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算输入字符串中 26 个小写字母中每个字母出现的次数。 不需要保留位置，因为任意交换让我们可以在必要时重新排列字符串。 
2. 处理来自`a`到`y`。 对于当前带有计数的字母`cnt[i]`， 保持`cnt[i] % 2`复制这封信并添加`cnt[i] // 2`复制到`cnt[i + 1]`。 这准确地表示执行当前角色的所有可能的合并。 
3. 使用更新后的计数继续处理下一个字母。 此步骤用于处理级联，例如`aaaa -> bb -> c`。 在某一级别创建的副本的处理方式与原始输入中存在的副本完全相同。 
4.留下计数`z`不变。 后面没有字符`z`，所以一对`z`无法转换字符。 
5. 通过迭代构建答案`z`下降到`a`并根据最终计数附加每个字符。 这种排序在字典顺序上是最大的，因为对于固定的多重集，将较大的字符放在前面总是会产生最大的字符串。 

为什么有效：处理信件后`i`，它的最终计数正是到达它的副本数的奇偶校验，而每个可能的对都已转换为下一个字符。 被丢弃的对并没有丢失，因为每个对都贡献了一份副本`i + 1`。 因此，不变量是字母表的已处理前缀已尽可能向上减少，每个剩余的对表示在下一个位置。 由于一旦其对向上进行，就无法进一步改进较低的字符，并且由于降序对于生成的多重集是最佳的，因此最终的字符串在字典顺序上是最大的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve(s: str) -> str:
    cnt = [0] * 26

    for ch in s:
        cnt[ord(ch) - ord('a')] += 1

    for i in range(25):
        cnt[i + 1] += cnt[i] // 2
        cnt[i] %= 2

    ans = []

    for i in range(25, -1, -1):
        if cnt[i]:
            ans.append(chr(ord('a') + i) * cnt[i])

    return ''.join(ans)

def main():
    s = input().strip()
    print(solve(s))

if __name__ == "__main__":
    main()
```这`cnt`数组存储每个字母的当前重数。 对输入进行计数需要遍历字符串一次，每个字符使用其 ASCII 值直接映射到索引。 

从索引开始循环`0`通过`24`执行从每个字母到其后继字母的进位操作。 该顺序至关重要。 加工时`b`，其计数可能已经包含由`a`，因此从低到高处理字母表会自动处理任意长的操作链。 

表达式`cnt[i] // 2`是可以合并的对的数量，而`cnt[i] % 2`是当前字符中必须保留的唯一数字。 Python整数在这里不存在溢出问题，并且每个计数最多是原始字符串长度。 

构建循环向后运行，以便首先出现较大的字母。 根据最终计数重复每个字符可以保留进位过程产生的准确的最终多重集。 

无需显式模拟交换。 它们在原始操作中的唯一目的是使相等的字符相邻，并且对字符进行计数已经为我们提供了相同的自由度，而无需构造中间字符串。

 ## 边缘情况

 对于输入`aa`，算法开始于`cnt[a] = 2`。 加工`a`携带一对到`b`并留下零`a`字符数，所以最终计数`b`是一。 输出是`b`。 仅对原始字符进行排序的解决方案将错误地返回`aa`，因为它永远不会考虑合并两个较低的字符会产生一个字典顺序更大的字符。 

对于输入`zz`，算法从不处理`z`作为利差来源。 它的计数保持等于二，并且递减结构产生`zz`。 通过在以下位置停止进位循环来处理边界`y`。 试图访问继任者`z`会创建无效字符或导致索引错误。 

为了`yyy`，计数`y`是三。 一对被带到`z`，留下一个`y`。 最终计数为`z = 1`和`y = 1`，所以结果是`zy`。 该算法保留奇数副本而不是丢弃它，这是每个字符的关键边界条件。 

为了`aaaa`，第一个进位改变四`a`人物一分为二`b`人物。 当算法达到`b`，这两个新生成的字符形成另一对并被传送到`c`。 结果是一个`c`。 这说明了为什么必须从左到右处理字母表：独立处理每个原始计数会错过之前创建的字符启用的操作。 

为了`aaz`, 两个`a`人物合而为一`b`，而原来的`z`保持不变。 最终的多重集是`{z, b}`，并且降序产生`zb`。 这证实了不需要首先对现有的最高字符执行该操作。 所有较低级别的进位都可以独立计算，然后合并到最终的排序中。 

对于仅包含`z`， 例如`z`，根本没有可能的操作。 计数数组保持不变，输出完全相同`z`，这也证实了该算法可以处理尽可能小的输入，而不依赖于任何现有的对。
