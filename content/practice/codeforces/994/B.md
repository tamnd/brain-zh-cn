 ## 解决方案
 ## 问题理解

 每个骑士都有两种属性：战斗力和金币。 骑士只能击败实力严格较小的骑士，每次胜利都会将被击败的骑士的硬币转移给获胜者。 然而，存在一个全局约束：没有骑士愿意击败超过`k`其他的。 

任务是想象每个骑士在这些规则下独立计划最佳的战斗序列，并计算每个骑士最终可以获得的最大硬币数量。 

输入给出了强度数组和按索引对齐的硬币值数组。 输出是另一个数组，其中每个位置对应于一个骑士，并包含从该骑士开始的最佳可实现总硬币数。 

这些约束强烈地塑造了解决方案空间。 对于多达 100,000 名骑士，任何试图模拟所有对之间战斗的方法都会立即变得二次且不可行。 一个天真的$O(n^2)$策略已经按照以下顺序执行$10^{10}$最坏情况下的比较，远远超出了一秒的时间限制所能容忍的。 额外的限制是$k \le 10$是关键的结构提示：每个骑士只对所有较弱骑士中极少数的最佳候选人感兴趣。 

当贪婪地思考而不按实力排序时，就会出现微妙的失败案例。 如果骑士只考虑附近的索引，它可能会错过输入顺序中较晚出现但实际上是有效目标的较弱的骑士。 例如，如果优势是`[10, 1, 2]`，第一个骑士可以击败其他两个骑士，但是基于位置的扫描而不排序会错误地将排序视为有意义。 另一个常见的陷阱是忽略“最多 k 杀”约束并简单地对所有较弱的硬币求和，当存在许多小价值的弱骑士并且只应选择少数高价值的骑士时，这种方法会失败。 

## 方法

 直接的解释是尝试让每个骑士与所有其他骑士对抗，检查哪些骑士较弱，然后选择最多的最佳子集`k`他们之中。 原则上这是正确的，因为它评估所有可能的有效选择，但它变得太慢，因为对于每个骑士，我们可能会扫描所有其他骑士，然后排序或选择最多`k`最佳候选人，总成本约为$O(n^2 \log n)$。 

结构的简化来自于约束的分离。 力量决定击杀的可行性，而金币则决定杀戮的欲望。 如果我们按照强度递增的顺序处理骑士，那么在我们处理一个骑士的那一刻，所有之前处理过的骑士都正是它允许杀死的骑士。 然后，问题简化为对于此排序的每个前缀，最多维护大小的最佳可能子集`k`按硬币价值。 

我们维护一个仅包含顶部的小结构，而不是从头开始重新计算每个骑士的最佳子集`k`迄今为止看到的所有较弱骑士的硬币价值。 自从`k`最多为 10，最小堆工作效率很高：它存储当前最好的候选者，每当出现新的较弱的骑士时，我们就决定它是否属于顶部`k`。 这将选择步骤变成了具有微小常数的对数时间。 

关键的转变是每个骑士的答案仅取决于属于严格较弱骑士的多组硬币，减少到其最佳状态`k`元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2 \log n)$|$O(n)$| 太慢了 |
 | 最佳|$O(n \log k)$|$O(k)$| 已接受 |

 ## 算法演练

 我们首先通过增加力量来重新排列骑士，以便骑士的所有有效目标都出现在它面前。 

1.将每个骑士的力量、金币和原始指数配对成一个结构，然后按强度对这些结构进行排序。 这保证了当我们处理一个马时，之前处理过的每个马都是严格较弱的。 
2. 维护一个最小堆，用于存储选定的较弱骑士的硬币值以及堆内容的运行总和。 堆永远不会包含超过`k`元素。 该结构代表了最佳的一组`k`到目前为止可用的杀戮。 
3. 按排序顺序迭代骑士。 在将当前骑士插入堆之前，将其答案计算为它自己的硬币加上当前堆总和。 这是可行的，因为此刻的堆恰好包含最好的`k`来自所有实力较弱的骑士的硬币。 
4. 将当前骑士币值插入堆中，并将其添加到运行总和中。 如果堆大小超过`k`，删除最小元素并从总和中减去它。 这样只保留最有利可图的`k`未来更强骑士的候选人。 
5. 处理完所有骑士后，使用存储的索引将结果恢复到原始顺序。 

中心思想是每个骑士在按强度排序的数组上查询前缀结构，其中前缀被持续维护为最多可能的最佳集合`k`硬币价值。 

### 为什么它有效

 当我们处理一个马时，堆恰好包含`k`在所有实力较小的骑士中，金币价值最大。 该骑士的任何最优策略都只能从这些较弱的骑士中进行选择，并且由于最多允许选择`k`，用最好的子集替换任何选定的子集`k`可用不能减少总数。 这表明堆始终代表所有未来骑士的最佳选择集，因此每个计算的答案都是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

n, k = map(int, input().split())
p = list(map(int, input().split()))
c = list(map(int, input().split()))

knights = [(p[i], c[i], i) for i in range(n)]
knights.sort()

heap = []
heap_sum = 0
ans = [0] * n

for power, coins, idx in knights:
    ans[idx] = coins + heap_sum

    heapq.heappush(heap, coins)
    heap_sum += coins

    if len(heap) > k:
        removed = heapq.heappop(heap)
        heap_sum -= removed

print(*ans)
```排序步骤确保我们在计算每个答案时只考虑有效的较弱对手。 堆始终存储其中可能最好的候选者，并且运行总和避免重复重新计算堆总数。 最小堆的使用至关重要，因为只要大小超过，它就可以有效地删除最无用的硬币价值`k`。 

一个常见的实现错误是在计算其答案之前将当前的马插入堆中。 这会错误地允许骑士在计算中“自杀”。 正确的顺序是先查询，再插入。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(n \log k)$| 每个马最多被推入并可能从一堆大小中弹出一次`k`|
 | 空间|$O(k)$| 堆只存储最好的`k`候选人 |

 该解决方案完全符合限制，因为`k`非常小，使得堆操作在实践中有效地保持恒定时间，即使对于$10^5$骑士。

 ## 边缘情况

 当`k = 0`，堆从不用于累积。 对于每个骑士来说，答案只是他们自己的硬币，算法自然会处理这个问题，因为在整个处理过程中堆保持为空。 

当所有强度在输入中按降序排列时，排序步骤将它们完全颠倒。 该算法仍然有效，因为它仅依赖于排序顺序，而不依赖于输入顺序。 每个骑士都会在处理之前正确地看到所有较弱的骑士。 

什么时候`k`等于`n-1`，堆可能会变大，但仍然受`k`。 该算法仍然正确地选择可能的最佳子集，因为考虑了每个较弱的骑士，并且堆保留了其中的最高值。
