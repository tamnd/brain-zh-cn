 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 在每个测试用例中都有多个骰子，并且每个骰子的面上都写有六个正整数。 当我们将骰子排成一排时，我们从每个选定的骰子中精确挑选一个面作为该骰子的“顶部”值。 我们的目标是选择骰子的子集，并为每个选定的骰子分配其面值之一，以便所选值形成一系列连续整数。 任务是最大化我们在这个序列中包含的骰子数量。 

重新解释该问题的一种有用方法是将每个骰子视为提供最多六个候选值，并且我们希望为每个选定的骰子选择一个值，以便最终的多重集可以无间隙地排序为最长的可能整数序列。 

总体而言，约束条件很大，所有测试用例中的骰子数量高达 200,000 个。 这立即排除了任何依赖于检查骰子的所有子集或跨骰子分配值的所有方式的任何事情。 即使是骰子上的二次方法也会太慢。 任何可行的方法都必须在接近线性的时间内处理每个芯片，并避免重复扫描全局结构。 

一个微妙的点是，不同的骰子可以共享值，甚至相同的骰子也可能出现多次。 这很重要，因为如果重复项多次出现相同的数字，则可以重复使用它们来延长连续运行。 

当骰子的值非常稀疏且不连续时，就会出现边缘情况。 例如，如果没有两个骰子共享任何连续兼容值，则答案会缩减为 1。另一个极端情况是当许多骰子包含重叠范围时，即使单个骰子不规则，也允许长链。 每个骰子的幼稚贪婪选择在这里可能会失败，因为同一个骰子可能支持多个不同的数字，并且过早提交可能会阻塞更长的链。 

## 方法

 暴力解释会尝试为每个骰子分配一个值，然后检查骰子的所有可能子集，看看哪些子集可以形成连续的序列。 即使我们固定了目标间隔，我们仍然需要决定哪个骰子贡献哪个数字，并且每个骰子有六个选项。 这会导致爆炸：大约 O(6^N) 次分配或至少 O(N · 2^N) 子集探索。 即使 N 是 50 左右，这也是不可行的，更不用说 200,000 了。 

关键的观察是，我们实际上并不需要使用所有骰子，并且每个骰子最多可以使用一次。 重要的是我们是否可以使用可用的骰子“覆盖”一个连续的整数区间，其中每个骰子最多贡献该区间的一个整数。 这将视角从分配的组合学转变为间隔的可行性问题。 

对于任何固定的整数值x，我们只需要知道哪些骰子可以产生x。 如果我们尝试从某个数字 L 开始构建一个连续的段，唯一的要求是对于段中的每个整数，我们至少有一个包含它的未使用的芯片。 这表明了一种贪婪的结构：尽可能地扩展当前段，总是为每个整数消耗一个可用的芯片。 

为了提高效率，我们为每个值预先计算包含该值的骰子列表。 然后，我们将每个值视为全局扫描中的一个位置，并贪婪地匹配骰子以延长最长的连续运行。 

问题简化为找到整数行上的最长间隔，以便我们可以将不同的骰子分配给其中的每个整数，并将每个骰子分配给它支持的值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解分配| O(6^N) | O(6^N) | O(N) | 太慢了|
 | 值索引贪婪匹配 | O(N log N) 或 O(N) | O(N) | 已接受 |

 ## 算法演练

1. 构建从任何骰子上出现的每个整数值到包含它的骰子索引列表的映射。 这将面选择转换为值和骰子之间的邻接信息。 这有帮助的原因是我们只关心骰子是否可以支持特定的数字，而不关心哪个面产生它。 
2. 对所有骰子上出现的所有不同值进行排序。 这为我们提供了一致的从左到右的顺序来尝试形成连续的段。 如果不进行排序，我们就无法可靠地尝试增加间隔。 
3. 扫描已排序的值并保持贪婪的尝试来构建连续的链。 对于起始值，我们尝试一次向前扩展一个整数，跟踪是否可以为每一步分配一个未使用的骰子。 
4. 对于当前值x，从包含当前链中未使用的x的骰子列表中挑选一个骰子。 将该骰子标记为已使用，然后继续执行 x + 1。如果不存在这样的骰子，则从所选起始值开始的链将在该点失败。 
5. 对排序值列表中每个可能的起始位置重复该过程，记录所达到的最大链长度。 答案是成功覆盖的连续整数的最大数量。 

微妙的设计选择是对骰子的重用限制。 一旦在链中使用骰子，它就不能在同一链中再次做出贡献，这强制了每个位置一个骰子的要求。 

### 为什么它有效

 该算法依赖于贪婪匹配不变量：对于从 L 开始的任何尝试的连续段，我们总是在扩展时为每个整数分配第一个可用的未使用的骰子。 如果在某个整数 x 处我们找不到有效的骰子，那么对先前选择的分配进行重新排列就无法在不违反早期分配的情况下解决此问题，因为每个较早的整数已经消耗了支持它的骰子，并且替换其中任何一个只会降低早期位置的灵活性。 这使得贪婪扩展对于固定开始而言是局部最优的，并保证第一个故障点是不可避免的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N = int(input())
        
        value_to_dice = defaultdict(list)
        dice = []
        
        for i in range(N):
            faces = list(map(int, input().split()))
            dice.append(faces)
            for v in faces:
                value_to_dice[v].append(i)
        
        # unique sorted values
        values = sorted(value_to_dice.keys())
        
        best = 0
        
        used = [False] * N
        
        # try each start
        for i in range(len(values)):
            # reset used for each attempt
            for j in range(N):
                used[j] = False
            
            start = values[i]
            cur = start
            length = 0
            
            # attempt to extend consecutive sequence
            while True:
                if cur not in value_to_dice:
                    break
                
                picked = -1
                for d in value_to_dice[cur]:
                    if not used[d]:
                        picked = d
                        break
                
                if picked == -1:
                    break
                
                used[picked] = True
                length += 1
                cur += 1
            
            best = max(best, length)
        
        print(f"Case #{tc}: {best}")

if __name__ == "__main__":
    solve()
```其实现直接遵循贪婪扩展思想。 这`value_to_dice`map 是中心结构，允许恒定时间访问可以产生给定整数的所有骰子。 

这`used`数组确保每个骰子在每次尝试的链中仅使用一次。 我们为每个起始值重置它，以便每次尝试都是独立的。 

内循环递增`cur`逐步停止，当某个值完全丢失或没有未使用的芯片可以支持当前值时停止。 

一个实际的问题是重置完整的`used`每次启动的数组可能很昂贵，但它使逻辑保持简单和正确。 在优化版本中，人们会使用时间戳或每次运行标记。

 ## 边缘情况

 当所有骰子共享一个共同值时，就会出现一种边缘情况。 对于每个骰子包含的输入`1`，映射将所有骰子分配给同一个整数。 该算法开始于`1`，选择一个骰子，然后立即找到没有未使用的骰子`2`，因此链长度仍为 1。任何重复使用同一芯片的尝试都会违反约束，因此这是正确的。 

另一种边缘情况是当值在骰子之间完美交错时，例如一个骰子覆盖所有奇数，另一个骰子覆盖所有偶数。 该算法自然地在它们之间交替，因为每个整数步骤都会查询该值的所有可用骰子并选择一个未使用的骰子，从而允许链的完全扩展。 

当值存在但在全局集中不连续时，就会出现第三种边缘情况。 例如，骰子可能只包含`10, 100, 1000`。 扫描仍然尝试每次启动，但每个扩展都会立即失败，因为`x + 1`映射中不存在，正确生成最大长度为 1。
