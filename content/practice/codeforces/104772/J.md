 ## 解决方案
 ## 问题理解

 我们得到了同一组青蛙坐在编号睡莲叶上的两张快照。 在第一个快照中，青蛙占据由严格递增数组给出的位置`a`，在第二个快照中，它们占据了另一个严格递增数组给出的位置`b`。 两张快照中的每个位置都是唯一的，因此在照片之间没有青蛙停留在同一个睡莲叶上。 

每只青蛙从某个位置移动`a`到某个位置`b`，在两个数组之间形成一对一的匹配。 每只青蛙要么严格向左移动，要么严格向右移动，因为两个数组之间没有共享坐标。 

任务不是重建匹配。 相反，我们只关心有多少青蛙向左移动。 我们必须列出该计数的所有值，这些值可以通过青蛙之间的某些有效匹配来实现。 

约束最多为 200,000 个元素，这排除了任何二次或三次匹配策略。 任何尝试所有排列甚至所有匹配的解决方案都是不可行的，因为双射的数量是`n`。 

一个天真的但重要的观察是，答案仅取决于两个排序数组如何在数轴上交错，而不取决于青蛙身份。 然而，粗心的推理常常假设向左移动的次数是固定的。 当间隔以某种方式重叠时，这是错误的。 

当阵列完全交错时，会出现微妙的边缘情况。 例如，如果`a = [1, 3, 5]`和`b = [2, 4, 6]`，任何青蛙`a`可以与任何青蛙匹配`b`具有一致的方向选择，允许多种可能的向左移动计数。 贪婪匹配会错误地建议固定计数。 

## 方法

 暴力方法会尝试分配每个元素`a`到一个独特的元素`b`并计算还剩下多少作业。 这是完全二分图中的完美匹配问题，并且枚举所有匹配是不可行的，因为有`n!`的可能性。 即使通过尝试所有分配来确定固定数量的左移动的可行性也会导致指数时间。 

关键的结构观察是只有数轴上点的相对顺序才重要。 如果我们合并`a`和`b`在单个排序序列中，我们得到一个标签模式，指示每个位置是属于第一张照片还是第二张照片。 该序列对所有约束进行编码。 

问题就相当于选择哪些元素`a`与较小的元素配对`b`。 一旦我们确定了有多少青蛙向左走，其余的青蛙就被迫向右走，但可行性取决于排序约束是否允许这样的分裂。 

关键的见解是，当从左到右扫描时，我们可以跟踪有多少只青蛙`a`和`b`已经被看到了。 在任何前缀处，必须已经在左方向匹配的青蛙数量受到以下限制：`b`元素已经出现在相应的之前`a`元素。 这将问题简化为计算一系列有效的前缀余额，这可以通过贪婪扫描来维护。 

我们在扫描合并数组时保持运行不平衡。 每个`a`贡献一个潜在的未来左移，每个`b`消耗一个。 有效的左移动次数对应于在不违反前缀可行性的情况下可以实现的所有可能的最终平衡。 这将问题简化为计算最小和最大可能的可行匹配流，并且之间的所有整数值都是可以实现的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力匹配枚举| O(n!) | O(n) | 太慢了|
 | 排序扫描 + 可行性范围 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 将两个数组合并为一个排序序列，同时将每个元素标记为来自`a`或者`b`。 这保留了所有可能运动的相对几何形状。 
2. 扫描合并序列并保持运行平衡，定义为有多少`a`已经看到的元素减去了多少`b`到目前为止已经看到了一些元素。 这个平衡代表了有多少无与伦比的青蛙`a`目前正在“等待”配对。 
3. 跟踪该天平在整个扫描过程中可以达到的最小值和最大值。 这些极值表示对有效匹配中可以共存多少左分配和右分配的结构约束。 
4. 将最终的余额约束转换为可能的左移动次数。 每个可行的配置对应于选择多少个`a`元素与之前的元素匹配`b`元素，有效余额的范围直接转化为可能答案的连续范围。 
5. 输出该范围内的每个整数值。 

### 为什么它有效

 在合并订单的每个前缀处，`b`已经出现的元素对之前出现的元素数量施加了下限`a`元素必须已经分配到右侧。 对称，保持无与伦比`a`元素定义仍然可以向左移动多少次。 

由于两个序列均已排序，因此任何可行的匹配都必须遵守前缀排序约束。 这些约束形成了可行的全球平衡的单一区间，而不是分散的可能性。 一旦确定了可实现的最小和最大不平衡，它们之间的任何整数都可以通过本地交换匹配决策来实现，而不会破坏前缀有效性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

events = []
for x in a:
    events.append((x, 0))
for x in b:
    events.append((x, 1))

events.sort()

balance = 0
min_balance = 0
max_balance = 0

for _, t in events:
    if t == 0:
        balance += 1
    else:
        balance -= 1
    min_balance = min(min_balance, balance)
    max_balance = max(max_balance, balance)

start = -min_balance
end = n - max_balance

ans = list(range(start, end + 1))

print(len(ans))
print(*ans)
```该解决方案首先将两个数组与标签合并以区分来源。 排序会重建两个快照中涉及的所有睡莲叶的完整从左到右结构。 

变量`balance`跟踪有多少`a`元素已经出现在前面`b`元素。 什么时候`balance`变成负数，意味着更多`b`已看到的元素多于可用的元素`a`候选人，迫使某些青蛙在任何有效的作业中都匹配到右边。 这就是我们记录最小值的原因。 

转型从`(min_balance, max_balance)`进入`[start, end]`将前缀约束转换为全局左移动计数。 端点将不平衡转化为绝对计数`0`和`n`。

 ## 边缘情况

 当所有`a`值小于所有值`b`值，每只青蛙都必须在任何有效匹配中向左移动，因此答案会折叠为单个值`n`。 扫描产生严格的非正平衡，最小`-n`和最大`0`，仅产生归一化后的终点。 

当所有`b`值小于所有值`a`价值观，每只青蛙都必须向右移动，只生产`0`作为有效答案。 余额始终保持非负数，给出最小`0`和最大`n`。 

当数组严格交替时，每个前缀在狭窄的走廊内保持平衡，并且算法输出完整连续范围的可能答案。 这直接来自于这样一个事实：前缀约束永远不会强制唯一的配对方向，从而允许可行匹配的连续变化。
