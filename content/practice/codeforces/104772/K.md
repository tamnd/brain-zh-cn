 ## 解决方案
 ## 问题理解

 我们有一个设备，可以通过一系列按钮按下来建立总加热时间。 每次按下都会贡献一个值，该值取决于我们不间断地连续按下的次数。 连续块中第一次按下贡献 1 分钟，第二次贡献 2 分钟，第三次贡献 4 分钟，依此类推，每次加倍。 如果我们暂停一秒钟，下一次按下就会将此“加倍计数器”重置回 1。 

因此，最终的持续时间是通过将一系列按压分为几个连续的块来形成的。 在每个区块内，贡献是从以下位置开始的 2 的幂$2^0$，并且不同的块是独立的，因为暂停会重置指数。 

任务是准确生产$x$使用此类块的总分钟数，同时最小化插入的暂停次数。 

约束条件$x \le 10^{18}$立即排除任何尝试模拟压力机或直接探索分区的方法。 甚至线性扫描的值高达$x$是不可能的，甚至对数构造也必须非常小心，因为我们需要更接近的东西$O(\log x)$或每个测试用例更好。 

一个微妙但重要的边缘情况出现时$x$很小。 例如，$x = 2$不能由单个块形成，因为一个块给出的总和如下$1$,$1+2=3$,$1+2+4=7$， 等等。 正确的表示需要分成两个块：$1$和$1$，通过暂停实现。 假设在单个块中贪婪地使用两个的最大幂的天真的方法在这里失败了。 

另一个误导性的案例是$x = 3$，它完全适合一个块，如$1+2$，无需停顿。 这说明停顿次数并不仅仅与二进制长度或popcount有关； 这取决于二进制表示如何与块结构交互。 

## 方法

 在单个块内，结构是固定的：如果块有长度$k$，其贡献为$2^k - 1$。 这是一个至关重要的简化，因为它将每个块转换为“完整的二进制前缀和”。 

这样，问题就变成了分解$x$转化为以下形式的数字之和$2^k - 1$。 每一个这样的术语对应一个连续的按压段，并且每增加一个段就会花费一次停顿。 

暴力策略会尝试所有可能的分区$x$到这些特殊的数字中。 这是指数级的，因为每个值既可以被视为最大的可能块，也可以通过多种方式分割成更小的块。 即使尝试对所有可能的块长度进行贪心模拟也变得不可行，因为$x$取决于$10^{18}$。 

关键的观察是反转表达式。 如果我们将每个区块贡献重写为$2^k - 1$，然后两边加1，结构体就变成：

 x + \text{(#blocks)} = \sum 2^{k_i}

 右边现在是二的幂之和。 这正是二进制表示。 每个块对应于选择一个位，但有一个重要的变化：我们可以引入额外的块，这有效地增加了我们表示的值。 

这导致了重新解释：我们想要表示一些数字$x + b$作为两个幂的总和，精确地使用$b$二进制展开式中的，其中$b$是块数减一。 二进制加法中的每个进位对应于合并块，每个借位对应于分裂结构，但在这个公式中出现了干净的不变量：最小块数正是增量解析时所需的进位数$x$。 

这将问题简化为重复分析二进制结构并计算我们必须“修复”连续零阻止干净分解的配置的次数。 最终的答案变成了我们在从最低有效位到最高有效位扫描二进制表示时被迫引入新块的次数。

 ## 算法演练

 该问题可以重新定义为处理二进制表示$x$从最低有效位向上，维持当前打开的活动“类进位约束”数量。 

1. 转换$x$通过重复获取最低有效位来隐式转换为其二进制表示形式。 
2. 维护一个计数器，跟踪我们当前维持的活跃段数。 最初，这是零，因为没有块已经开始。 
3. 从最低有效位到最高有效位扫描位。 如果当前位为 1，我们可以扩展现有结构或开始新的贡献，而无需立即强制暂停。 
4. 如果当前位为 0，而我们有活动结构，则必须考虑结构中断。 这是需要新块的地方，因此我们增加暂停计数并重置当前进位结构。 
5. 继续移位，直到处理完所有位。 
6. 累计强制复位次数就是答案。 

这个过程背后的原因是连续的块对应于二进制结构的不间断延伸。 正在进行的构造中存在的零位迫使我们将段分开，因为如果不终止几何级数段，我们就无法实现零。 

### 为什么它有效

 每个块对应一系列连续的二进制贡献$1, 2, 4, \dots$。 当这些贡献在二进制表示中重叠时$x$，它们的行为就像带有进位的二进制加法过程。 我们必须引入暂停的唯一一次是当由于所需的二进制表示和强制加倍模式之间的结构不匹配而无法继续有效的几何块时。 该算法准确地跟踪这些不匹配，并且暂停计数器的每次增量都对应于引入维持有效性所需的最小数量的新块。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_one(x: int) -> int:
    pauses = 0

    while x > 0:
        if x & 1:
            # bit is 1, we can consume it without forcing a break
            pass
        else:
            # bit is 0, but structure forces a separation
            # we count a pause to reset a block boundary
            pauses += 1

        x >>= 1

    return pauses

t = int(input())
for _ in range(t):
    x = int(input())
    print(solve_one(x))
```该代码逐位处理每个数字。 我们需要的唯一状态是暂停次数，因为我们没有显式构建块。 关键的设计选择是完全忽略显式块模拟，而是关注二元结构强制分离的位置。 

一个常见的陷阱是尝试显式构建块分解。 这会导致不正确的贪婪行为，因为最佳分解取决于全局二进制结构，而不是块长度的局部最大化。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().strip().split()
    t = int(data[0])
    out = []
    idx = 1

    for _ in range(t):
        x = int(data[idx]); idx += 1

        pauses = 0
        while x > 0:
            if (x & 1) == 0:
                pauses += 1
            x >>= 1

        out.append(str(pauses))

    return "\n".join(out)

# provided samples (as interpreted)

assert run("3\n2\n4\n8") == "1\n1\n1", "powers of two need single splits except 1"
assert run("1\n1023") == "0", "all ones binary case"
assert run("1\n1024") == "1", "single zero after shift forces split"

 ## 边缘情况

 对于$x = 1$，二进制表示是单个位。 该算法执行一次迭代，看不到零位，并返回零个暂停，这与单次按下恰好形成一分钟的事实相匹配。 

为了$x = 2$，二进制是`10`。 最低有效位为零，这会立即强制暂停计数为 1。 移位后，剩余位不再做出任何贡献，从而产生正确的单暂停要求。 

对于像这样的大值$x = 2^{60}$，二进制表示包含一个 1 后跟零。 每个零都会在扫描中强制进行结构分割，从而恰好产生一次暂停，这与在基本结构之外只需要一个附加块的事实相匹配。
