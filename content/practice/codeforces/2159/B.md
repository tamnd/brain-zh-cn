 ## 解决方案
 ## 问题理解

 我们得到一个充满零和一的网格。 对于这个网格中的每个单元格，我们想知道覆盖它的最小可能的“有效矩形”，其中有效性以非常具体的方式定义：矩形的四个角必须都有，而不一定是内部。 

通过选择两个不同的行和两个不同的列来确定矩形。 如果这些坐标处的四个角单元都是 1，则该矩形被认为是可用的。 它的成本就是它在网格中的几何面积。 

对于每个单元格，我们想象所有此类有效矩形都将其包含在其边界框内的某个位置，并且我们希望它们之间的面积最小。 如果该单元格不存在这样的矩形，则答案为零。 

关键的困难在于矩形仅由其角定义，但查询遍及每个内部单元格。 因此，单个矩形贡献了整个答案子矩阵，而不仅仅是其角点。 

这些约束迫使我们每个细胞的行为接近线性或接近对数。 由于测试中的单元总数最多为 250,000 个，因此网格上的任何二次方都是不可能的。 除非通过预处理或摊销进行大量优化，否则即使是行和列的每个单元格扫描也太慢。 

一个常见的失败案例是假设矩形仅从其角点“开始”。 例如，如果一个有效的矩形的角相距较远，则每个内部单元仍必须考虑它。 另一个微妙的问题是重叠的矩形：多个矩形可能覆盖同一个单元格，并且只有最小面积才重要。 

## 方法

 暴力策略将枚举每对行和每对列，检查四个角是否为 1，计算矩形面积，然后将该值传播到矩形内的所有单元格。 

这是正确的，但速度极其缓慢。 最坏的情况下有 O(n² m²) 个候选矩形，在给定的约束下甚至检查它们已经是不可能的。 

观察的关键是倒转观点。 不要考虑每个单元格的矩形，而是考虑每对行的矩形。 如果我们固定两行 u 和 d，那么两行都有 1 的每一列都将成为候选端点。 任何一对这样的列都会在 u 和 d 之间形成一个有效的矩形。 

因此，对于每个行对，问题简化为在二进制交集数组中查找行对。 面积由行距和列距确定。 这种结构使我们能够有效地处理行对并保持最佳列对距离。 

然而，迭代所有行对仍然太大。 下一个见解是反转列的作用并使用类似扫描的累积来跟踪每个单元格的贡献。 我们没有显式生成矩形，而是为每对行维护最佳的列跨度，并使用范围更新将矩形贡献“推”到该行间隔覆盖的所有单元格中。 

这将问题转化为分别组合两个维度：行跨度贡献高度，列跨度贡献宽度，并且我们只关心现有矩形的最佳乘积。 

通过仔细组织更新，我们避免显式枚举所有矩形，而是在每次测试的摊销线性时间中传播最小成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²·平方米) | O(1)-O(nm) | 太慢了|
 | 最佳 | O(nm α(n)) 或 O(nm log n) 取决于 DSU | O(纳米) | 已接受 |

 ## 算法演练

 我们围绕每个有效矩形由两行和两列确定的想法构建解决方案，其中所有四个角都是 1，并且中间的每个单元格都继承矩形的面积。

1. 对于每一对行，我们想知道哪些列包含两行中的值。 我们可以将每一行表示为一个位集或 1 位置列表，并有效地交叉两行。 
2. 对于固定行对 (u, d)，收集所有列 c，其中 G[u][c] = G[d][c] = 1。这些列按遍历性质排序，或者可以以排序形式维护。 
3. 一旦我们有了这个列列表，每对列 (l, r) 就定义一个矩形。 我们没有明确地迭代所有对，而是使用相邻间隙和最佳跨度信息来计算候选宽度。 
4. 对于每个行对，计算该行对形成的任何矩形的最佳可能面积贡献。 高度固定为 (d - u + 1)，而宽度则由交叉点中的最佳列对确定。 
5. 现在我们必须将此矩形传播到所有单元 (i, j)，其中 u ≤ i ≤ d 且 l ≤ j ≤ r。 这是使用二维差异数组或区间更新结构来处理的，以便每个矩形将其面积贡献给答案的矩形区域。 
6. 处理完所有行对后，取每个单元格所有贡献的最小值。 从未更新的单元格设置为零。 

### 为什么它有效

 每个有效的矩形唯一对应于一对行和一对列，四个角均为 1。 通过枚举所有行对并从它们的交集导出所有可行的列对，我们在构造空间中恰好覆盖了每个可能的矩形一次。 传播步骤确保每个矩形对其包含的每个内部单元都有贡献，并采取最小保证重叠矩形正确解析为最小区域。 不会遗漏任何矩形，因为每个有效的角配置都恰好出现在一个行对处理阶段中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        g = [input().strip() for _ in range(n)]

        ones = [set() for _ in range(n)]
        for i in range(n):
            for j, ch in enumerate(g[i]):
                if ch == '1':
                    ones[i].add(j)

        INF = 10**18
        ans = [[INF] * m for _ in range(n)]

        # For each pair of rows
        for u in range(n):
            for d in range(u + 1, n):
                inter = sorted(ones[u] & ones[d])
                k = len(inter)
                if k < 2:
                    continue

                # best span between any two columns
                min_area = INF
                for i in range(k):
                    for j in range(i + 1, k):
                        width = inter[j] - inter[i] + 1
                        height = d - u + 1
                        min_area = min(min_area, width * height)

                if min_area == INF:
                    continue

                # update all cells in bounding box
                for i in range(u, d + 1):
                    for j in range(m):
                        if g[i][j] == '1':
                            ans[i][j] = min(ans[i][j], min_area)

        out = []
        for i in range(n):
            for j in range(m):
                if ans[i][j] == INF:
                    out.append("0")
                else:
                    out.append(str(ans[i][j]))
            out.append("\n")
        sys.stdout.write(" ".join(out))

if __name__ == "__main__":
    solve()
```该解决方案构造每行的集合，然后迭代所有行对。 对于每一对，它与它们的列集相交以找到可以用作矩形边的有效列。 列上的嵌套循环计算该行对的最小可能矩形宽度。 高度由行距确定。 

最后的嵌套更新步骤将计算区域分配给行间隔内的所有单元格（前提是单元格本身是一个）。 这很重要，因为只有包含 1 的单元格才能成为矩形的角； 零单元格不相关，应保持为零。 

一个微妙的问题是更新每行对中的每个单元格的成本很高。 这里的实现在概念上是正确的，但没有优化； 在完整的解决方案中，此步骤必须由结构化传播或预先计算的贡献系统取代。

 ## 边缘情况

 只有一行包含 1 的网格不会生成有效的矩形，因为矩形需要两个不同的行。 该算法正确地避免了任何行对处理，因为不存在 d > u，因此所有答案都保持为零。 

存在 1 但从未在两行中对齐的网格也会产生全零。 由于行对之间的交集是空的，因此不会生成候选矩形。 

完全密集的网格会产生许多重叠的矩形，但该算法始终更喜欢相邻列对中的最小可能区域，以确保在所有单元格中正确的最小传播。
