 ## 解决方案
 ## 问题理解

 任务是使用基于 gcd 和 lcm 的数论配对规则组合由正整数索引的两个序列。 从概念上讲，输出中的每个位置表示从输入数组中的位置对聚合的值，但不是通过相等的索引或移位进行配对，而是通过索引之间的算术结构来确定配对。 

该问题的一部分要求最大公约数等于给定值的所有对的贡献。 另一部分对称地要求最小公倍数等于给定值的所有对的贡献。 每个有效对将两个数组中相应值的乘积贡献到由 gcd 或 lcm 条件确定的恰好一个输出桶中。 

因此，这不是对索引相加的经典卷积，而是对整数除数格的卷积。 答案的结构完全取决于值在除数和指数倍数上的分布方式。 

如果最大索引达到约 10^5 或类似值，则所有索引对的二次对枚举将变得不可行。 甚至$10^5$元素意味着$10^{10}$配对检查，这远远超出了任何实际的时间限制。 因此，解决方案必须重新组织计算，以便每对都不会被显式迭代，而是以除数或倍数的分组形式聚合贡献。 

当试图将 gcd 或 lcm 条件视为对索引的简单算术约束而不考虑多重性时，就会出现一种微妙的失败情况。 例如，如果我们仅根据每个数字的除数独立地累积贡献，则我们可能会重复计算共享多个除数关系的对。 

考虑一个小场景，其中数组索引为 1..6，我们计算 gcd 贡献。 对 (2,4) 的 gcd 为 2，但它也通过共享除数 1 间接做出贡献。不隔离精确 gcd 类的简单除数求和方法会错误地将这一贡献放入多个存储桶中，而不是恰好一个。 正确的公式必须确保每一对仅对其所属的确切 gcd 或 lcm 类别做出贡献。 

## 方法

 蛮力方法很简单。 对于每对索引$i, j$，我们计算$\gcd(i,j)$或者$\mathrm{lcm}(i,j)$并添加$a[i] \cdot b[j]$到相应的输出桶。 这是正确的，因为它直接遵循卷积的定义。 但是，它需要迭代所有索引对，这会导致$O(n^2)$运营。 什么时候$n$达到$10^5$，这导致$10^{10}$无法在时间限制内运行的操作。 

关键的观察结果是 gcd 和 lcm 条件定义了可以使用除数和多重关系重新索引的整数对的分区。 我们不再以成对的方式思考，而是转换视角：固定一个值$d$，并将所有可整除的索引分组$d$。 每个索引都可以写成以下的倍数$d$，并且 gcd 或 lcm 约束可以通过这个缩小空间中的变换索引来表达。 

这就是除数变换变得强大的地方。 通过累加每个除数倍数的值，我们可以将成对条件转换为独立求和。 对于基于 gcd 的聚合，我们首先计算共享公约数的所有对的贡献，然后使用莫比乌斯反演减去多算的贡献。 对于基于 lcm 的聚合，我们颠倒了观点：我们累积倍数并仔细地将贡献分配给正确的最小公倍数类。 

整个问题简化为执行少量结构化除数和变换，而不是枚举对。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(n)$| 太慢了|
 | 最优（除数变换 + 莫比乌斯）|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们描述了 gcd 卷积的计算； lcm 版本遵循除数和倍数之间角色的对称颠倒。 

1.初始化一个数组`F[d]`累积指数为以下倍数的所有对的贡献`d`。 对于每个值`d`，我们收集所有可整除的指数`d`，因为gcd和lcm约束可以通过这些共享除数组来分解。 
2. 对于每个除数`d`，迭代所有倍数`i = d, 2d, 3d, ...`并累计总和`a[i]`放入临时数组中`Adiv[d]`。 做同样的事情`b[i]`进入`Bdiv[d]`。 此步骤将原始数组压缩为除数空间表示。 
3. 对于每个`d`，计算初步对贡献`F[d] = Adiv[d] * Bdiv[d]`。 这计算了两个指数至少共享除数的所有对`d`，这意味着他们的 gcd 是`d`，不一定等于`d`。 这是一个被高估的数量，但以一种有用的方式构建。 
4. 按降序对除数应用莫比乌斯求逆。 对于每个`d`, 减去所有倍数的贡献`k*d`从`F[d]`。 这精确地隔离了那些 gcd 恰好为的对`d`，删除 gcd 严格较大的对的贡献。 
5. 由此产生的`F[d]`现在表示每个值的精确 gcd 卷积结果`d`。 
6.对于lcm卷积，我们反转视角。 我们不是按公约数分组，而是按共享倍数分组。 我们计算除数向上的贡献，并使用类似筛子的传播将它们分配为倍数，以便每一对都为其最小公倍数贡献一次。 

正确性依赖于这样一个事实：每对整数对应于唯一的 gcd 类和唯一的 lcm 类，并且除数闭包允许我们将这些类表示为多个集合上的线性组合。 

不变量是在处理一个值之后`d`，所有超出的严格倍数`d`已被删除，只留下 gcd 恰好为的对的贡献`d`。 由于除数晶格按降序处理，因此较高的 gcd 贡献在从较低的 gcd 贡献中减去之前已完全解析，从而防止任何循环依赖性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXN = 100000

def solve():
    n = int(input())
    a = [0] * (MAXN + 1)
    b = [0] * (MAXN + 1)

    arr = list(map(int, input().split()))
    for i in range(1, n + 1):
        a[i] = arr[i - 1]

    arr = list(map(int, input().split()))
    for i in range(1, n + 1):
        b[i] = arr[i - 1]

    Adiv = [0] * (MAXN + 1)
    Bdiv = [0] * (MAXN + 1)

    for d in range(1, n + 1):
        s = 0
        for i in range(d, n + 1, d):
            s += a[i]
        Adiv[d] = s

    for d in range(1, n + 1):
        s = 0
        for i in range(d, n + 1, d):
            s += b[i]
        Bdiv[d] = s

    F = [0] * (MAXN + 1)

    for d in range(n, 0, -1):
        F[d] = Adiv[d] * Bdiv[d]
        k = 2 * d
        while k <= n:
            F[d] -= F[k]
            k += d

    print(*F[1:n + 1])

if __name__ == "__main__":
    solve()
```代码首先将每个数组压缩为除数和形式，其中每个位置`d`存储可被整除的索引处的所有条目的总和`d`。 这将原始对空间转换为除数格表示。 

乘法步骤构建了一个过度计数的结构，其中`F[d]`包括至少共享除数的所有对`d`。 然后，减法循环通过向下迭代来消除所有更严格除数的贡献，确保首先解决更高的倍数。 这个顺序很重要，因为每个`F[k]`在从除数中减去它之前需要它。 

一个常见的陷阱是迭代`d`反转时向上。 这将尝试减去尚未完全纠正的值，从而通过晶格传播错误的计数。

 输入：```
n = 4

```我们计算除数和。 

| d | 阿迪夫[d] | Bdiv[d] | 减法前的 F[d] |
 | ---| ---| ---| ---|
 | 4 | 4 | 1 | 4 |
 | 3 | 3 | 2 | 6 |
 | 2 | 6 | 4 | 24 |
 | 1 | 10 | 10 10 | 10 100 | 100

 现在减去倍数。 

对于 d = 2：减去 F[4] → 24 - 4 = 20

 对于 d = 1：减去 F[2] 和 F[3] 和 F[4] → 100 - 20 - 6 - 4 = 70

 最终：

 | d | F[d] |
 | ---| ---|
 | 1 | 70 | 70
 | 2 | 20 |
 | 3 | 6 |
 | 4 | 4 |

 该跟踪显示了如何在解决较低的除数贡献之前删除较高的除数贡献，匹配每个 gcd 类仅在处理所有严格倍数之后才被隔离的不变量。

 ## 边缘情况

 关键的边缘情况是当所有值都放置在小数字的倍数的索引处时，例如所有非零条目仅出现在偶数位置。 在这种情况下，奇数除数之和保持为零，只有偶数除数才能累积贡献。 该算法自然地处理这个问题，因为奇数除数永远不会收到任何质量`Adiv`或者`Bdiv`，因此它们永远不会产生虚假的 gcd 贡献。 

另一个微妙的情况是当数组的索引处有一个非零条目时`n`。 唯一的非零除数桶是`n`，并且反转步骤仅沿着除数链干净地传播该贡献`n`。 这证实了不相关除数链之间不会发生交叉污染，因为每个索引仅参与其自身除数结构的倍数。
