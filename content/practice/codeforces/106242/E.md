 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并可以任意更改元素，每次更改都算作一次操作。 目标是修改数组，以便数组的每个连续段都至少包含一个在该段内仅出现一次的值。 

换句话说，不允许任何子数组“局部全部重复”。 如果选择任何间隔，则必须能够指向其中的一个值，该值在该间隔内的频率恰好为 1。 

关键的压力在于这种情况是极其全球性的。 单个重复模式可能会破坏许多重叠的子数组，并且修复一个违规可能会意外地在其他地方引入另一个违规。 

这些约束意味着我们需要每个测试用例接近线性或线性算数的东西。 当总长度高达 3⋅10^5 时，任何超过 n 的二次方都是不可能的。 即使 O(n log n) 解决方案也需要仔细论证，而 O(n) 或 O(n α(n)) 方法才是现实的目标。 

一种简单的方法是尝试在每次修改后模拟所有子数组，甚至通过扫描所有 O(n^2) 段来重新计算有效性。 这显然太大了：即使对于 n = 10^5，我们也会查看大约 10^10 个子数组。 

一个不太天真的想法是仅在本地检查“坏模式”，但困难在于子阵列的有效性取决于频率结构，而不是邻接性。 

查看问题的一个有用方法是翻转它：不要确保每个子数组都有唯一的元素，而是考虑子数组何时失败。 当子数组中的每个不同值至少出现两次时，子数组就是坏的。 这意味着所有不同的值在区间内“配对”，因此不存在单例。 

全局结构变成：我们必须销毁每个元素出现的重数至少为 2 的所有区间。 

## 方法

 蛮力的观点很简单。 对于修改后的每个可能的数组，我们将扫描所有子数组并使用哈希图检查频率计数。 如果直接完成，则成本为 O(n^3)；如果使用前缀频率结构，则成本为 O(n^2)。 即使针对每个查询进行优化，我们仍然必须考虑 θ(n^2) 间隔，这远远超出了限制。 

关键的观察结果是，坏子数组是由值的重复出现引起的。 如果一个值出现多次，它会创建许多候选区间，而它可能不会贡献一个单例。 保证每个子数组都有唯一元素的唯一方法是打破足够的重复，以便重复结构的长链不能形成完全“覆盖”的区间。 

一种更具结构性的观点是考虑保留尽可能多的原始元素，同时确保没有值形成可以完全覆盖重复区间的模式。 如果我们将每个值解释为在一条线上出现，则违规来自于出现间隔之间的重叠。 为了打破所有完全覆盖的间隔，我们必须“剪切”足够多的出现次数，以便重叠不能完全平铺任何段。 

这将问题转化为选择要保留的位置子集，以便在剩余数组中每个间隔都包含一个仅出现一次的值。 同样，我们希望删除尽可能少的位置，以便剩余结构避免任何完全“双重覆盖”的区间。 

如果我们从左到右扫描并确保每当一个值以可能形成完全覆盖段的方式重复时，我们就会删除一个事件以打破该链，就会出现一个有用的贪婪视角。 最佳策略最终与元素的频率过剩相关，但不是全局的：只有能够维持完全重复间隔的碰撞才是重要的。

表达最佳解决方案的一种更简洁的方法是观察在任何有效的最终数组中，每个值在受控配置中最多可以出现两次，并且出现两次以上的配置不可避免地会创建一个完全重复的段。 这将任务简化为计算必须删除多少超出安全结构的“额外”事件。 

我们将每个值的初始重数与可以安全嵌入而不会创建错误子数组的值进行比较。 每个值在有效结构中最多贡献两次可用的出现； 除此之外的一切都必须修改。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（检查修改后的所有子数组）| O(n3) 或 O(n2·n) | O(n) | 太慢了|
 | 基于频率的贪婪归约 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算数组中每个不同值的出现频率。 这捕获了每个值对潜在重复模式的贡献次数。 
2. 对于每个值，计算超出安全容量的出现次数。 安全容量来自于重复值不能形成完全“非唯一元素”子数组的结构要求，这迫使我们限制一个值可以参与的次数，而不会创建不可避免的重叠模式。 
3. 对值中所有超额出现次数进行求和。 每一次多余的出现都对应于打破重复链所需的一次修改，否则该重复链将参与到错误的子数组中。 
4. 返回总修改量作为答案。 

聚合步骤背后的直觉是，由不同值创建的冲突不会以允许共享修复的方式进行干扰。 每个过量的事件都会独立地影响潜在的完全重复间隔，因此必须单独解决它们。 

### 为什么它有效

 不变的是，在处理值并删除所有多余的出现之后，任何值都不能以支持完全由重复元素组成的子数组的方式出现。 任何子数组必须至少包含一个值，其剩余出现次数在该间隔内被隔离，因为每个值都受到约束，因此它不能两次“覆盖”一个间隔而不留下一个单例。 由于每个坏子数组都需要所有参与值的重复项完全覆盖，因此消除多余的重复项会破坏所有此类构造。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1
        
        # key idea: each value can safely contribute up to 2 occurrences
        # beyond that, we must modify elements
        ans = 0
        for v, c in freq.items():
            if c > 2:
                ans += (c - 2)
        
        print(ans)

if __name__ == "__main__":
    solve()
```该实现纯粹是频率驱动的。 唯一微妙的部分是对“2”阈值的解释，它来自这样一个事实：一旦一个值出现三次或多次，它不可避免地会产生重叠间隔，其中该值本身无法保证包含这些出现的每个子数组中的单例。 

我们从不直接模拟子数组。 所有结构都被压缩为频率约束，这使得解成为线性的。 

## 工作示例

 ### 示例 1

 输入：```
3
2 1 2
```我们计算频率：2 出现两次，1 出现一次。 没有值出现超过 2 次，因此无需修改。 

| 价值| 频率| 过剩|
 | ---| ---| ---|
 | 1 | 1 | 0 |
 | 2 | 2 | 0 |

 答案是0。 

这证实了该阵列已经避免了病态的重复结构。 

### 示例 2

 输入：```
4
4 4 4 4
```频率：4 出现 4 次。 我们必须将其减少到最多 2 次可用的出现。 

| 价值| 频率| 过剩|
 | ---| ---| ---|
 | 4 | 4 | 2 |

 答案是2。 

这反映出，在不破坏两次出现的情况下，存在完全由重复的 4 组成的子数组，因此无法保证每个区间都有唯一的元素。

 ## 边缘情况

 关键的边缘情况是所有元素都相同。 在这种情况下，每个子数组都由单个重复值组成，因此满足条件的唯一方法是大幅减少重数。 该算法通过计算所有超过两次的出现次数来处理此问题，因此结果可以与 n 正确缩放。 

另一个特殊情况是值恰好出现两次。 这些对答案没有贡献，因为两个事件仍然可以共存，而不会强制缺少单例的完全重复的子数组。 

大小为 1 的最小输入也能正确运行，因为单个元素很容易形成一个子数组，其中该元素是唯一的。
