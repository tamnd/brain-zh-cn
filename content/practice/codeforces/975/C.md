 ## 解决方案

 ## 问题理解

 我们正在模拟一排战士的反复战斗。 每个战士都有固定的生命值，箭总是击中第一个还活着的战士，然后再射向下一个。 当一名战士累积的伤害等于或超过他的生命值时，他被视为死亡，并在同一分钟内继续攻击下一个战士。 

不同之处在于，如果所有战士在那分钟内死亡，则战斗会在每一分钟后“重置”。 届时，所有战士会在下一分钟开始前立即恢复完全健康。 然而，如果一些战士在一分钟结束后幸存下来，他们减少的生命值会持续到下一分钟。 

对于每一分钟，我们需要报告在处理该分钟的箭头后有多少战士仍然活着，同时考虑到前几分钟遗留下来的任何部分伤害。 

输入大小使得简单的模拟变得不可能。 由于有多达 200,000 名战士和 200,000 分钟，并且箭数每分钟高达 10^14，任何单独处理每个箭或从头开始重复扫描的解决方案都会太慢。 即使 O(nq) 方法也有 4e10 次操作的风险，这是不可行的。 

当一分钟的箭足以杀死所有战士并且仍然有剩余时，就会出现一种微妙的边缘情况。 在这种情况下，剩余的箭将被丢弃，所有战士都会复活。 粗心的实施可能会错误地将损坏延续到下一分钟或无法正确重置。 

另一个棘手的情况是当伤害仅部分杀死战士时。 该战士将在下一分钟成为新的“当前目标”，并且他的剩余生命值必须正确持续。 缺少这种持久性会导致后续查询中的计数不正确。 

## 方法

 暴力模拟将通过从第一个活着的位置迭代战士并逐个减去箭头来处理每分钟，直到箭头用完或所有战士都死了。 如果一个战士的生命值达到零，我们就会转移到下一个战士。 这种方法是正确的，但在最坏的情况下，每分钟可以遍历所有 n 个战士，并且每个战士可能在几分钟内被访问多次，从而导致 O(nq) 行为。 200,000 x 200,000 这是完全不可行的。 

关键的观察是，伤害只会从左向右移动，一旦战士被完全杀死，他就不会再变得相关，除非发生完全重置。 这建议在前几分钟后维护剩余生命值的前缀结构，并快速找到当前的箭波可以传播多远。 

我们可以维护生命值的前缀总和并跟踪到目前为止已累积的总伤害，而不是逐箭头模拟。 每分钟的箭头都会增加全局伤害计数器。 第一个还活着的战士索引是前缀总和超过累积伤害的第一个位置。 这将问题简化为在前缀和数组中重复查找边界，这可以使用二分搜索来完成。 

然而，当一分钟内传入的箭头总数超过总剩余生命值时，我们还需要处理重置。 在这种情况下，所有战士都会死亡，我们会将累积伤害重置为零，因为一切都会复活。 

因此，问题变成了维护全局“到目前为止的损害”，并回答有多少前缀总和仍然高于它，并在损害超过总和时定期重置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(nq) | O(n) | 太慢了 |
 | 前缀和+二分查找 | O(q log n) | O(q log n) | O(n) | 已接受 |

 ## 算法演练

 1.构建前缀和数组`pref`， 在哪里`pref[i]`是战士的总生命值，从 1 到 i。 这让我们知道杀死某个特定点需要多少伤害。 
2. 维护一个变量`d`代表当前状态下的总损坏。 
3. 对于每个查询`k_i`， 增加`d`经过`k_i`，因为箭头不断累积伤害，直到发生重置。 
4.如果`d`大于或等于`pref[n]`，所有战士都会在这一分钟内死亡。 在这种情况下，输出`n`并重置`d`为零，因为完全死亡后会立即复活。 
5. 否则，我们需要找出有多少战士在受到伤害后还活着`d`。 我们找到最小的索引`pos`这样`pref[pos] > d`使用二分查找。 
6. 存活战士数量为`n - pos + 1`，因为之前所有的战士`pos`都死了，剩下的还活着。 
7. 输出当前分钟的该值并继续。 

二分搜索步骤至关重要，因为它将动态前缀损坏过程转换为静态有序结构查询。 

### 为什么它有效

 前缀总和数组准确地编码了杀死每个战士所需的累积伤害。 由于伤害总是从左到右发生并且永远不会向后跳，因此条件`pref[i] <= d`准确地描绘了死去的战士的特征。 活动段始终是后缀，因此单个边界索引可以完整描述状态。 重置条件保留了正确性，因为一旦所有战士死亡，系统状态就会变得与初始状态相同，使得过去的伤害变得无关紧要。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
a = list(map(int, input().split()))

pref = [0] * (n + 1)
for i in range(1, n + 1):
    pref[i] = pref[i - 1] + a[i - 1]

total = pref[n]
d = 0

import bisect

for _ in range(q):
    k = int(input())
    d += k

    if d >= total:
        print(n)
        d = 0
        continue

    pos = bisect.bisect_right(pref, d)
    alive = n - (pos - 1)
    print(alive)
```前缀总和数组将所有战士强度压缩为单调结构，其中每个前缀代表一个完整的击杀阈值。 变量`d`累积几分钟内的总传入箭头，直到发生完全擦除，此时我们会重置，因为系统状态会重新启动。 

二分查找（`bisect_right`）找到第一个严格大于当前伤害的前缀，这直接标识了第一个活着的战士。 减去可以有效地得出幸存者的数量。 

一个微妙的细节是在执行二分搜索之前正确处理重置。 如果我们忘记重置`d`当所有战士都死后，未来的查询将错误地对已重置的系统施加伤害。

## 测试用例```python
import sys, io
import bisect

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + a[i - 1]

    total = pref[n]
    d = 0

    out = []
    for _ in range(q):
        k = int(input())
        d += k
        if d >= total:
            out.append(str(n))
            d = 0
        else:
            pos = bisect.bisect_right(pref, d)
            out.append(str(n - (pos - 1)))

    return "\n".join(out)

 ## 边缘情况

 一个关键的边缘情况是，单个查询提供的箭头在概念上多次超过总运行状况。 该算法通过立即重置来处理这个问题`d >= total`，确保跨周期无残留损坏泄漏。 例如，与`a = [1,1,1]`和`k = 10`，我们设置`d = 0`并正确输出所有活着的战士。 

另一个边缘情况是损坏恰好落在前缀和边界上。 因为我们使用`bisect_right`， 如果`d`等于`pref[i]`, 战士`i`被认为已死亡，下一个战士将成为第一个活着的战士。 这符合箭矢在前进之前将战士完全耗尽的规则。
