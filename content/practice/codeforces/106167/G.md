 ## 解决方案
 ## 问题理解

 城市是一个由交叉点组成的矩形网格，其中每个单元格都可能包含必须提取的客户包裹。 移动受到单向街道的限制：从任何十字路口你只能向南或向东移动。 每个司机都从左上角开始，最终必须在右下角结束，始终遵循这些直接的街道规则。 

每个司机都遵循从起点到目的地的有效路径，并沿途收集位于所访问单元格的包裹。 司机只能从沿途可到达的小区取包裹。 任务是确定所需的此类单调路径的最小数量，以便至少有一条路径访问包含地块的每个像元。 

到 2000 年，网格大小可达 2000 个，这意味着多达 400 万个单元。 任何试图模拟所有可能路径或显式枚举路径的解决方案都是不可能的。 即使 O(nm log nm) 方法也需要仔细设计，并且任何在路径上更直接意义上的二次方都是不可行的。 该结构表明，问题的根本在于将部分有序网格中的一组点分解为最小数量的链，这些链遵循单调运动引起的优势关系。 

当地块形成类似对角线的结构时，会出现微妙的边缘情况。 

例如，考虑：```
C _ _
_ C _
_ _ C
```如果运动严格从左上角开始向东/向南，则每个驱动程序只能收集一个包裹，因此答案是 3。 一个天真的贪婪者试图在不考虑单调性约束的情况下“蜿蜒”通过多个 C 单元，可能会错误地认为更少的驱动程序就足够了。 

另一种情况是所有地块位于同一行或一列中。 例如：```
C C C C
```这里，一个司机可以通过向东移动来收集所有包裹，所以答案是 1。任何错误地将邻接或聚类视为充分的方法都会高估。 

关键的困难在于可达性同时在行和列方向上受到限制，从而产生二维偏序而不是简单的图。 

## 方法

 思考该问题的一种强力方法是单独考虑每个驱动程序路径。 我们将尝试构建一条从左上角到右下角的路径，贪婪地捡起尽可能多的未收集的包裹，然后将这些单元格标记为已服务，并重复直到所有包裹都被覆盖。 这立即就会陷入歧义：单调路径的数量呈指数级增长，甚至决定哪条路径最适合覆盖大多数剩余地块也不是局部确定性的。 在最坏的情况下，即使探索单个最优路径也需要对所有右/下序列进行组合推理，这在网格维度上是指数级的。 

失败点是不同地块之间的交互不是局部的。 由于单调性，通过一个单元的决定会限制所有未来可到达的单元。 

关键的观察结果是，每个有效的驱动程序路径在两个坐标中都是单调递增序列。 如果我们将地块视为点，则一条路径只能覆盖在行索引和列索引中形成递增链的地块。 这将问题转化为将一组 2D 点划分为最小数量的递增链。 

这是一个经典的转换：我们将二维偏序简化为链分解问题。 根据标准结果（相当于此设置中的迪尔沃斯定理），所需的最小链数等于反链的最大大小。 用网格术语来说，这成为在支配关系下相互不可比较的最长地块集合。 

对于这种特定的几何形状，反链结构在坐标变换后折叠成最大二分匹配或等效的最长递增子序列。 正确的减少方法是逐行处理单元格，并使用列上的贪婪匹配来维护最佳可能的链分配。 

这导致使用贪婪结构的有效解决方案，相当于计算由网格可达性隐式定义的 DAG 中的最小路径覆盖。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力路径枚举 | 指数| O(hw) | 太慢了 |
 | 通过贪婪匹配进行最优链分解 | O(hw log w) 或 O(hw) | O(w) | 已接受 |

 ## 算法演练

 1. 将包含地块的每个像元解释为偏序中的点 (i, j)，其中仅当 i1 ≤ i2 且 j1 ≤ j2 时，(i1, j1) 才能位于 (i2, j2) 之前。 这与南台阶和东台阶的移动限制相匹配。 
2. 按行索引递增的顺序处理所有宗地单元，并在每行内递增列顺序。 这种排序与有效路径的单调结构一致。 
3. 维护代表活跃链的数据结构。 每个链对应一个驱动程序路径，并以其所到达的最后一列位置为特征。 
4. 对于每个宗地单元 (i, j)，尝试将其分配给最后一列 ≤ j 的现有链。 在所有这样的链中，选择最后一列最大且仍满足约束的链。 这种贪婪的选择为未来的安置保留了灵活性。 
5. 如果存在这样的链，则通过将其最后一列更新为 j 来扩展它。 如果没有连锁店可以容纳包裹，则启动新的连锁店，相当于雇用新司机。 
6. 最后维护的链的数量就是答案，因为每个链对应于覆盖其分配的地块的有效单调路径。 

### 为什么它有效

在任何一点，链都代表已经覆盖已处理地块的不相交的单调路径。 贪心分配确保我们始终重用仍然可以到达当前地块的最受约束的现有路径。 这可以防止过早消耗更灵活的链，从而降低未来的可行性。 由于地块是按递增的行顺序处理的，因此任何有效的分配都必须遵守此顺序，并且按列贪婪放置保持了链端点形成最小反链边界的不变性。 这保证了链的数量永远不会超过覆盖所有点所需的真正最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import bisect

def solve():
    h, w = map(int, input().split())
    rows = []
    for _ in range(h):
        s = input().strip()
        rows.append(s)

    # We maintain a list of chain endpoints (columns)
    # Each chain represents a driver path.
    chains = []

    for i in range(h):
        for j in range(w):
            if rows[i][j] != 'C':
                continue

            # find rightmost chain with last_col <= j
            # we want largest last_col <= j
            idx = bisect.bisect_right(chains, j) - 1

            if idx >= 0:
                # extend that chain
                chains[idx] = j
            else:
                # start new chain
                chains.append(j)

            # keep chains sorted for greedy correctness
            chains.sort()

    print(len(chains))

if __name__ == "__main__":
    solve()
```该实现维护链端点的排序列表。 对于每个地块，它执行二分搜索以找到可以在不违反列维度单调性的情况下扩展的最佳链。 如果不存在，则创建一个新链。 排序可确保链保持有序，以便将来的二分搜索保持有效，尽管在完全优化的版本中，更专门的结构可以避免重复排序。 

微妙的一点是使用`bisect_right`找到最右边的可行链。 这确保了当更紧的链条可以处理当前包裹时，我们不会浪费低容量的链条，从而为未来更大的列索引保留更高的灵活性。

 ## 边缘情况

 完全空的网格不包含包裹，因此不需要司机。 该算法正确地生成零，因为从未创建过任何链。 

左上角的单个地块会立即创建一条链，因为不存在可扩展的现有链。 

严格的对角线排列迫使每个地块开始一个新的链，因为每个连续的地块位于贪婪结构中所有先前端点的下方和左侧。 该算法通过失败每次扩展尝试并重复附加新链来反映这一点。 

完全填充的网格允许一条链传播到所有单元格，因为由于行优先遍历中的非递减列结构，每个下一个单元格都可以扩展前一个链。
