 ## 解决方案

 ## 问题理解

 我们得到一系列沿直线排列的位置，其中每个位置可能包含也可能不包含平台。 玩家从最左边的位置开始，想要到达最右边的位置。 玩家只能向右移动，并且可以从任何当前位置向前跳跃，但只能跳跃到固定的最大距离。 

不同的是，玩家不需要降落在每个位置。 他们只需要降落在包含平台的位置上，并且每次跳跃都必须准确地降落在平台上。 没有平台的位置实际上无法用作着陆点，尽管它们仍然存在潜在的距离差距。 

任务是确定是否可以使用一系列有效跳跃从第一个位置行进到最后一个位置，如果可能，则构建一个代表着陆点的平台索引序列。 

输入描述了多个测试用例。 每个测试用例都会给出位置数量和最大跳跃距离，后面跟着一个数组，指示哪些位置包含平台。 输出必须打印有效的着陆位置序列或指示不可能。 

这些约束足够大，以至于平台之间所有跳跃的任何二次模拟都会失败。 每个测试用例最多有 10^5 个位置，任何检查所有平台对或尝试所有跳转组合的方法在最坏的情况下都会导致大约 10^10 次操作，这在时间限制内是不可行的。 

当平台稀疏时，就会出现一个关键的微妙之处。 例如，如果位置 1、2 和 100 处存在平台，并且最大跳跃为 10，则即使其他部分存在中间平台，也无法到达位置 100。 需要一个总是跳转到最远可达平台的贪心选择； 否则，幼稚的短步策略可能会过早陷入困境并错误地得出失败的结论。 

另一种边缘情况是第一个或最后一个位置不包含平台。 在这种情况下，不会立即存在解决方案，因为起点和终点必须是有效的着陆点。 

## 方法

 暴力方法会将每个平台建模为图中的一个节点，并尝试所有可能的转换：从每个平台，尝试跳转到距离 k 内的每个后续平台。 这有效地构造了一个有向无环图，其中跳跃范围内的任意两个平台之间都存在边。 然后将使用 BFS 或 DFS 来查找从第一个平台到最后一个平台的路径。 

正确性很简单，因为它探索了所有有效的转换。 然而，边的数量可以是平台数量的二次方。 如果有 n 个平台密集聚集，每个平台可以连接到 O(n) 个其他平台，从而产生 O(n^2) 条边。 即使构建这个图也超出了内存限制，并且遍历它也太慢了。 

关键的观察是，我们不需要明确考虑从给定点开始的所有可到达的平台。 相反，我们只关心每一步可到达的最远平台。 由于当前位置和最远可到达平台之间的所有平台在可行性方面都是等效的（它们只会减少剩余范围），因此始终选择最远可到达的有效平台可以保持可达性，同时最大限度地减少跳跃次数。 

这就把问题变成了贪婪扫描：维护一个指向当前平台的指针，并重复前进到距离k内的最远平台。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(n^2) | O(n^2) | 太慢了|
 | 最优贪心 | O(n) | O(n) | 已接受 |

 ## 算法演练

1. 提取平台存在的所有索引并将它们存储在列表中。 这将问题压缩为仅使用有效的着陆点。 
2. 检查第一个位置是否有平台。 如果没有，旅程就无法开始，所以答案立即是不可能的。 
3. 在第一个平台索引处初始化一个指针，并开始用它构建路径。 
4. 从当前平台开始，向前扫描平台列表，找出与当前平台距离不超过 k 的所有平台。 
5. 在这些可到达的平台中，选择最远的一个。 这种选择可以最大化进度并防止被中间选择阻碍。 
6. 将指针移至所选平台并将其附加到答案路径。 
7. 重复此过程，直到到达最后一个平台或无法取得进一步进展。 
8.如果在任何步骤都没有可达的前向平台，则终止并输出不可能。 

### 为什么它有效

 正确性依赖于每次跳跃后算法始终站在当前可行范围内最远可达平台的不变量。 任何有效的解决方案还必须从相同的可达间隔中选择其下一个着陆点。 选择更近的平台只能限制未来的到达范围，而不能扩大它，因为它减少了后续跳跃可用的剩余前进距离。 因此，如果存在解决方案，则每一步总有一个遵循贪婪选择，并且算法永远不会消除可行路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        if a[0] == 0 or a[-1] == 0:
            print(-1)
            continue

        # collect platform positions (1-indexed for output clarity)
        pos = [i + 1 for i, v in enumerate(a) if v == 1]

        res = []
        i = 0
        res.append(pos[i])

        possible = True

        while pos[i] != n:
            j = i
            # extend as far as possible within k
            while j + 1 < len(pos) and pos[j + 1] - pos[i] <= k:
                j += 1

            if j == i:
                possible = False
                break

            i = j
            res.append(pos[i])

        if not possible:
            print(-1)
        else:
            print(*res)

if __name__ == "__main__":
    solve()
```该代码首先将输入过滤到有效平台位置列表中。 这避免了重复检查无效单元格，并将问题减少为对有效索引的单调扫描。 

指针`i`在此压缩列表中跟踪当前平台。 内循环前进`j`在距离限制的情况下尽可能远`pos[j + 1] - pos[i] <= k`成立。 这就直接实现了选择最远可达平台的贪心步骤。 

如果`j`不移动，则跳跃范围内不存在前进平台，这会立即强制失败。

 ## 边缘情况

 当第一个或最后一个位置缺少平台时，就会出现关键的边缘情况。 例如，输入`1 5 / 0 1 1 1 1`立即失败，因为没有有效的起点。 该算法在任何处理和输出之前都会检查这一点`-1`，防止浪费计算。 

当平台存在但间隔刚好超出跳跃限制时，会出现另一种情况。 例如，`1 0 0 0 1`和`k = 2`没有有效的中间着陆点。 指针从第一个平台开始，在内层扫描中找不到可到达的下一个平台，触发失败条件`j == i`。 

第三种情况涉及密集的平台集群。 这里，算法可能在范围内有许多候选者，但仍然每一步仅前进一次到最远的可达候选者。 这确保了即使在最坏情况的密集段中，指针仍然单调地向前移动，而无需重新访问任何平台，从而保持线性行为。
