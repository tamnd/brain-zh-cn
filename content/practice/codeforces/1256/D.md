 ## 解决方案

 ## 问题理解

 我们得到一个二进制字符串和相邻交换的预算。 每次交换都会交换两个相邻的字符，并且每次这样的交换都会消耗一个预算单位。 我们的目标是将字符串按字典顺序重新排列成尽可能小的二进制字符串，同时遵守允许执行的交换次数的限制。 

这里的字典顺序是通常的字符串比较：我们想要尽可能多的前导`0`s 尽可能的，并且在具有相同前缀的字符串中，我们更喜欢推送的字符串`1`尽可能向右。 

重新解释操作的一个有用方法是考虑移动每个`0`左对面`1`s。 每当一个`0`通过一个`1`，它只花费一次交换。 这立即表明问题在于在预算允许的范围内贪婪地向左推进零。 

限制总的来说很大：所有测试用例的总长度可达一百万，并且每个测试允许的交换次数可以大到$n^2$。 这排除了任何模拟交换或以二次方式重复扫描字符串的方法。 甚至一个$O(nk)$每个测试用例的模拟是不可能的，因为$k$可以是巨大的。 每次测试我们都需要一个线性或接近线性的策略。 

当多个零争夺早期位置时，就会出现一个微妙的陷阱。 如果不考虑全局剩余预算，总是将当前零尽可能向左移动的天真贪婪策略可能会失败。 另一个常见的错误是逐步模拟交换，即使对于适度的输入，也会爆炸成二次行为。 

## 方法

 蛮力方法实际上是贪婪地执行交换。 人们可以重复扫描该字符串，并且每当`10`找到模式，如果我们还有预算，就交换它。 这会产生正确的字典顺序改进，因为每次交换都会局部改进顺序。 然而，在最坏的情况下，比如像这样的字符串`111...1000...0`，每个零必须交叉许多个，并且执行的交换次数可以是$n^2$。 每次交换还需要扫描或更新位置，导致每个测试用例的复杂性呈二次或更差，这是不可行的。 

关键的观察是我们永远不需要显式地模拟交换。 相反，我们从左到右处理零，并根据当前前面有多少个零以及剩余的预算来决定每个零可以向左移动多远。 每个零消耗的预算等于`1`它会跳过，但除了减少剩余预算之外，它不会干扰早期的决策。 

我们可以维护一个结构，跟踪已经放置了多少个零以及还有多少个可以交叉。 一个更清晰的观点是迭代字符串，同时维护一个类似队列的待处理零结构和可用交换的运行计数，贪婪地放置`0`只要预算允许，就尽量靠左。 

另一个等效且更易于实施的想法是模拟从左到右构建答案。 在每个位置，我们决定是否可以带一个`0`从某个未来位置进入当前位置。 我们贪婪地选择最早可达的`0`可以使用剩余的掉期将其移动到当前位置。 

这导致了一个过程，我们扫描字符串，维护仍有多少个零未使用，并针对每个位置决定是否可以在剩余成本约束下将零“拉入”其中。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力交换 |$O(n^2)$|$O(1)$| 太慢了|
 | 贪婪预算安置 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 在扫描字符串时预先计算所有的位置`0`s。 我们会考虑将它们按出现顺序向左移动。 
2. 维护指针`i`正在构造的最终答案和原始字符串中的另一个指针为零。 还维护一个变量`k`代表剩余的掉期预算。 
3. 对于每个位置`i`从左到右，决定哪个字符应该占据它。 我们想要`0`如果可能的话，因为它最大限度地减少了字典顺序。 
4. 决定是否`0`可以放置在位置`i`，计算移动下一个未使用的成本`0`定位`i`。 该成本是其原始位置和当前位置之间未移动的字符数。`i`，这实际上等于交叉干预必须执行的交换次数`1`s。 
5. 如果该成本小于或等于剩余成本`k`，我们放置`0`在位置`i`，消耗该成本，并使零指针前进。 否则，我们放置`1`并继续。 
6. 继续，直到所有位置都被填满。 

步骤 4 背后的关键思想是每个`0`在从左到右的结构中独立移动，其移动成本仅取决于它跳过了多少个位置。 通过始终在可承受的情况下选择下一个可用的零，我们确保较早的位置尽可能获得零，这正是词典最小化所要求的。 

### 为什么它有效

 该算法保持贪婪不变量：在每个位置，如果可以放置一个`0`在剩余预算内使用一些有效的交换序列，算法将这样做。 任何最佳解决方案还必须放置一个`0`在这种情况下，因为将其替换为`1`只会推一个`0`在不节省预算的情况下进一步向右，可以更早地改善词典顺序。 由于交换仅影响相对顺序并且每个`0`到达较早位置的成本是固定的，贪婪地消耗最便宜的可用物品`0`保持局部和全局最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n, k = map(int, input().split())
        s = input().strip()

        zeros = []
        ones_before = 0

        for i, ch in enumerate(s):
            if ch == '0':
                zeros.append(i)

        z = 0
        used = [False] * n
        res = []

        for i in range(n):
            # cost to bring next zero here
            if z < len(zeros):
                pos = zeros[z]
                cost = pos - i
                if cost <= k:
                    res.append('0')
                    k -= cost
                    z += 1
                    continue
            res.append('1')

        print("".join(res))

if __name__ == "__main__":
    solve()
```该实现预先计算所有零的位置，然后贪婪地决定是否可以将下一个未使用的零移动到当前位置。 表达式`pos - i`捕获根据相邻交换必须将零向左移动多远。 如果预算允许，我们就放置； 否则我们放置`1`。 

一个微妙的点是我们从不明确模拟交换。 成本计算隐含地考虑了所有所需的相邻交换。 这就是使解保持线性的原因。

 ## 边缘情况

 当字符串以多个开头时，就会出现一种边缘情况`1`s 并且有少量`0`离右边很远。 该算法仍然表现正确，因为前几个位置只能填充`1`直到积累了足够的预算来拉动`0`向前。 

另一个边缘情况是当`k`非常大。 在这种情况下，每个零在其最早可能的位置变得可以承受，并且该算法退化为生成一个完全排序的字符串，其中所有`0`是在前面。 

第三种情况是接近尾部时零密集。 即使存在多个零，每个零也只会被考虑一次，并且它们的成本会降低为`i`增加，确保不会错误地跳过零或重复计算零。
