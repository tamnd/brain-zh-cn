 ## 解决方案

 ## 问题理解

 我们得到了一份学生技能值列表，我们必须将这些学生分成几组，使每个学生都属于一个组，并且每组至少有三名学生。 对于每个组，其成本定义为该组内最大和最小技能值之间的差异。 目标是将数组划分为有效的组，以便所有组成本的总和尽可能小，并输出学生到达到该最小值的组的任何有效分配。 

输入大小高达 200,000，这会立即排除任何显式尝试所有分区甚至所有分段的解决方案。 任何二次或更差的 DP 都会超时，因此解决方案必须接近 O(n log n) 或 O(n)。 

一个关键的结构观察是分组仅在排序后才有意义，因为组的成本仅取决于最小值和最大值，而不取决于位置。 但是，我们仍然必须输出原始索引的标签，因此我们稍后会将分配映射回来。 

一个幼稚的错误是尝试从左到右贪婪地形成固定大小为三的组。 这会失败，因为有时扩展组比启动新组更能稍微降低总成本。 另一种失败模式是贪婪地合并相邻元素而不考虑未来的节省，这会破坏最优性，因为稍大的组可以廉价地吸收高成本元素。 

贪婪失败的例子：

 输入：```
6
1 2 3 100 101 102
```如果我们贪婪地形成大小为 3 的组，我们会得到 [1,2,3] 成本 2 和 [100,101,102] 成本 2，总计 4。这在这里是最佳的，但在其他模式（如 [1,2,3,10,11,100]）中，提前强制拆分可能会导致次优分组。 正确的解决方案必须在全局范围内决定群体边界，而不是局部范围。 

## 方法

 如果我们忽略效率，我们可以尝试对排序位置进行动态规划。 令 dp[i] 表示划分前 i 个排序学生的最小成本。 我们将尝试所有以 i 结尾且大小至少为 3 的最后组，对于 j ≤ i - 3，给出 dp[j] + (a[i] - a[j+1]) 形式的转换。这是正确的，因为按排序顺序，段中的最小值和最大值是其端点。 

然而，这种方法的复杂度为 O(n^2)，因为每个状态最多考虑 n 个转换。 当 n = 2e5 时，这是不可能的。 

关键的观察结果是，在任何最佳解决方案中，组都对应于按排序顺序的连续段。 一旦排序，段 [l, r] 的成本就是 a[r] - a[l]。 所以DP本质上是选择分割点，但我们需要强制最小分段大小为3。 

我们可以使用贪婪 DP 技巧来改进转换。 我们不考虑所有先前的状态，而是认为每个组必须在位置 i 结束，并且必须从某个 j ≤ i - 2 开始。成本变为 dp[j] + a[i] - a[j]，因此我们希望最小化 dp[j] - a[j]。 这简化为在有效 j 值上维持运行最小值，给出 O(n)。 

我们还需要重建，因此我们存储每个 i 的最佳先前切割点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对所有细分市场进行强力 DP | O(n²) | O(n) | 太慢了|
 | 具有最小前缀的优化 DP | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们首先根据技能值对学生进行排序，同时记住他们的原始指数。 排序是必不可少的，因为它保证任何最佳组都将按此顺序对应于连续的段。 

然后，我们使用动态规划，其中 dp[i] 表示划分前 i 个已排序学生的最小总成本。 我们还维护一个指针 choice[i]，指示状态 i 的最后一组的开始位置。 

我们强制每个组的大小至少为 3，因此当我们计算 dp[i] 时，最后一个组必须从某个位置 j ≤ i - 2 开始。 

该转换利用了组 [j, i] 的成本为 a[i] - a[j] 的事实，因此：

 1. 初始化 dp[0] = 0 并将所有其他 dp 值设置为无穷大。 
2. 对于从 1 到 n 的每个 i，我们考虑是否可以形成以 i 结尾的有效最后组。 
3. 我们在 dp[j] - a[j] 的有效 j 上保持运行最佳值。 
4. 当 i ≥ 3 时，我们使用迄今为止看到的最佳 j 来更新 dp[i]：dp[i] = a[i] + best。 
5. 我们还存储哪个 j 给出了这个最佳值，以便稍后重建组。 

填充 dp 后，我们通过使用存储的分割点从 n 向后行走来重建组。 每个分段对应一个团队，我们为该分段中的所有成员分配一个唯一的团队 ID。 

为什么它有效：一旦数组被排序，每个最佳组都可以被假设为一个连续的段，因为在组之间交换元素不能减少范围之和。 DP 确保对于每个端点 i，我们选择最佳的有效起点 j，并且运行最小保证我们在考虑大小约束的同时有效地考虑所有可行的启动。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # sort with original indices
    arr = sorted([(a[i], i) for i in range(n)])

    INF = 10**18
    dp = [INF] * (n + 1)
    parent = [-1] * (n + 1)

    dp[0] = 0

    best_val = INF
    best_idx = -1

    # we maintain dp[j] - arr[j]
    for i in range(3, n + 1):
        j = i - 3
        val = dp[j] - arr[j][0]
        if val < best_val:
            best_val = val
            best_idx = j

        dp[i] = best_val + arr[i - 1][0]
        parent[i] = best_idx

    # reconstruct groups
    res_groups = []
    i = n
    while i > 0:
        j = parent[i]
        res_groups.append((j, i))
        i = j

    res_groups.reverse()

    # assign team ids
    ans = [0] * n
    team_id = 1

    for l, r in res_groups:
        for k in range(l, r):
            ans[arr[k][1]] = team_id
        team_id += 1

    total = 0
    for l, r in res_groups:
        total += arr[r - 1][0] - arr[l][0]

    print(total, len(res_groups))
    print(*ans)

if __name__ == "__main__":
    solve()
```该代码首先对学生进行排序，同时保留原始索引。 DP 循环通过维持 dp[j] - a[j] 的滚动最小值来构建最佳分区，这表示以 i 结尾的段的最佳可能起点。 

重建阶段使用父指针向后移动，恢复精确的段边界。 最后，为每个分段分配一个团队 ID，并根据分段端点计算总成本。 

一个微妙的实现细节是索引：dp 是基于 1 的排序数组位置，而原始索引是单独存储的。 错误地混合这两个空间是常见的错误来源。
