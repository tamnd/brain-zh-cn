 ## 解决方案
 ## 问题理解

 我们得到了一组机器人、一组被称为“比特”的难以区分的物品，以及几个收银员。 每个机器人必须分配给一名收银员，并且每个收银员最多只能服务一个机器人。 在分配之前，我们还决定如何在机器人之间分配比特，限制是每个比特都是不可分割的，并且每个参与的机器人必须至少接收一个比特。 分布在所有活动机器人上的总位数必须等于全部输入量。 

每个收银员都有三个参数。 首先，最大容量 Mi 限制单个机器人可以为收银员带来的比特数。 其次，每比特处理时间Si。 第三，固定开销 Pi，每个机器人应用一次，无论它带来多少位，只要它至少为 1 且最多为 Mi。 如果机器人将 N 位交给收银员 i，则该机器人的完成时间为 Si × N + Pi。 

所有机器人在零时间并行启动，目标是最小化最后一个机器人完成的时间。 由于机器人在分配后不会进行交互，因此这是一个调度问题，涉及我们如何分配工作（位）和如何分配处理器（收银员）之间的耦合。 

这些约束立即表明对分配进行天真的枚举是不可能的。 如果有多达 1000 个出纳员和多达 10^9 位，任何显式尝试所有分布或所有分配的方法都会发生组合爆炸。 我们必须利用的结构是机器人 R 的数量才是真正的瓶颈，而不是位数 B 或收银员 C 的数量。 

当收银员处理小货物时表现出色，但处理大货物时却很糟糕时，就会出现微妙的失败案例。 例如，具有较小 Si 但较大 Pi 的收银员可能最适合许多小型任务，但无法处理大包裹。 另一个边缘情况是当许多收银员的 Mi 为 1 时，强制每个机器人严格限制一位，这将问题转化为纯粹的分配排序。 

## 方法

 一种直接的暴力解释是将每个 B 位分配给 R 个机器人，然后将每个机器人分配给不同的收银员。 即使我们固定收银员分配，将 B 个不可区分的物品分配到具有容量的 R 个箱子中也是 B 的指数，大致约为 R^B 的量级。 当 B 达到 10^9 时，这立即变得不可行。 

即使我们忽略比特分配，只关注将机器人分配给收银员，我们仍然面临组合匹配问题。 关键的复杂性在于，收银员的成本取决于它接收的比特数，因此我们无法预先计算每个收银员的单个重量。 

关键的观察是，R 相对于 C 足够小，我们可以考虑选择 R 收银员并决定每个收银员接收多少位。 我们不是直接分配位，而是推断收银员处理不同可能负载所需的总时间。 对于固定的收银员 i 和目标时间 T，我们可以问它在时间 T 内完成时可以处理多少位。这个不等式是 Si × N + Pi ≤ T，从而得出 N ≤ (T − Pi) / Si，并且 N ≤ Mi。 因此，收银员 i 在期限 T 下的有效能力是 T 的单调函数。 

这将问题转化为可行性检查：给定候选时间 T，我们是否可以在最多 R 个选定收银员之间分配 B 位，以便每个收银员 i 最多接收 cap_i(T) 位？ 如果我们能回答这个问题，我们就可以对 T 进行二分搜索。 

剩下的困难是选择使用哪个 R 收银员。 对于固定的 T，每个收银员贡献一个容量 cap_i(T)。 我们希望最大的 R 容量之和至少为 B。这是最优的，因为任何最优分配都将使用能够在截止日期内处理最多比特的 R 出纳员。

这样解决方案就变成了按时二分查找，每次检查计算能力并通过排序取出顶部的R。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力分配| O(C^R·B) | O(C^R·B) | O(1) | O(1) | 太慢了|
 | 二分查找+贪心容量检查 | O(C log maxT log C) | O(C log maxT log C) | O(C)| 已接受 |

 ## 算法演练

 1. 固定一个候选答案T，代表所有机器人允许的最大完成时间。 目标是测试是否可以分配所有 B 位，以便每个机器人在 T 内完成。 
2. 对于每个收银员 i，计算机器人在 T 时间内完成任务时可以带多少位。即 N_i = min(Mi, max(0, (T − Pi) // Si))。 如果 T < Pi，则收银员根本无法为任何机器人服务，因此其容量为零。 
3. 将 N_i 视为收银员 i 在截止时间 T 下的可用容量。每个收银员最多可以使用一次，因此我们最多选择 R 个收银员并将其容量相加。 
4.将所有N_i值按降序排序。 
5. 获取最高的 R 值并计算它们的总和 S(T)。 如果S(T)≥B，则可以在时间T内分配所有比特； 否则是不可能的。 
6. 在 T 上使用二分搜索。下限可以从 0 开始，上限可以安全地设置为所有收银员的 max(Pi + Mi × Si)。 
7. 可行性成立的最小 T 就是答案。 

### 为什么它有效

 对于固定的T，每个收银员独立定义其可以支持的最大负载。 由于机器人和收银员最多使用一次，因此问题减少为选择最多 R 个独立容量以最大化位的总覆盖范围。 任何最佳解决方案都必须使用 R 最大容量，因为用更大容量的未使用收银台替换所选收银台永远不会降低可行性。 此交换参数确保贪婪选择对于可行性检查是最佳的。 T 中的单调性保证了二分查找的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(T, R, B, cashiers):
    caps = []
    for m, s, p in cashiers:
        if T < p:
            caps.append(0)
        else:
            caps.append(min(m, (T - p) // s))
    caps.sort(reverse=True)
    return sum(caps[:R]) >= B

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        R, B, C = map(int, input().split())
        cashiers = [tuple(map(int, input().split())) for _ in range(C)]

        lo, hi = 0, 0
        for m, s, p in cashiers:
            hi = max(hi, p + m * s)

        while lo < hi:
            mid = (lo + hi) // 2
            if can(mid, R, B, cashiers):
                hi = mid
            else:
                lo = mid + 1

        print(f"Case #{tc}: {lo}")

if __name__ == "__main__":
    solve()
```可行性检查实施于`can`。 它将每个收银员转换为时间 T 下的容量，然后贪婪地选择最佳 R。二分搜索是在答案空间上完成的，因为可行性是单调的：如果时间 T 有效，则任何更大的时间也有效。 

一个常见的陷阱是在计算容量时忘记 Mi 约束。 另一个是当 T < Pi 时错误地使用整数除法，它必须明确地钳位到零。 上限必须同时包含 Pi 和 Mi × Si； 否则二分查找可能会错过正确的范围。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(C log(maxT) log C) | O(C log(maxT) log C) | 每次可行性检查都会对 C 值进行排序，并且二分搜索会在时间范围内运行 |
 | 空间| O(C)| 存储每张支票的容量数组 |

 约束允许最多 1000 个出纳员和高达 10^9 的大值，但在大约 60 次二分搜索迭代内重复排序 1000 个元素是足够快的。 该解决方案避免了对 B 的直接依赖，这一点至关重要，因为 B 可以大到 10^9。

 ## 边缘情况

 当所有收银员的 T 都小于 Pi 时，就会出现一种边缘情况。 在这种情况下，每个容量都变为零，并且算法正确地返回不可行，因为顶部 R 容量的总和为零。 这可以防止任何分配被过早接受。 

另一种情况是当 Mi 很大但 Si 也很大时。 即使收银员在技术上可以获取许多位，时间约束也会在小 T 下抑制其有效容量。可行性检查通过公式 (T − Pi) // Si 自然地处理这个问题，直到 T 与 Pi 相交，该公式才变为零。 

最后一种情况是，B 在某个阈值 T 处恰好等于 R 个最佳收银员的能力总和。因为检查使用大于或等于，所以相等被正确地视为可行，确保二分搜索收敛到最小有效时间而不是超调。
