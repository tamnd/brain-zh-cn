 ## 解决方案
 ## 问题理解

 我们得到了几块长方形的饼干。 每个饼干都会将其周长贡献给总“脆度分数”，并且我们可以在烘烤前选择修改每个饼干。 修改是穿过矩形中心的单次直线切割，产生面积相等的两块。 这些块不需要保持矩形，但它们的周长是明确定义的。 

目标是对于每个饼干选择是保持不变还是应用单次切割，以便所有所得碎片的周长总和尽可能大而不超过目标值$P$。 初始配置最多已经有总周长$P$，所以我们总是有一个有效的基线。 

关键的数量是我们通过切割一次矩形获得多少额外的周长。 每个 cookie 都独立地提供一个选择：采用其基本周长或支付“成本”将其升级到更大的周长。 全局问题变成在类似背包的约束下选择这些升级的子集，但容量正是我们可以将总周长增加多少$P$。 

这些限制意味着最多 100 个测试用例，每个用例最多 100 个 cookie。 对所有切割组合的简单指数搜索将涉及$2^{100}$国家，这是不可行的。 即使是一个具有容量的伪多项式背包$10^8$直接是不可能的，因此唯一可行的方法是使用增益值中的结构来压缩状态空间。 

当矩形非常薄或非常倾斜时，就会出现微妙的边缘情况。 在这种情况下，与周长相比，切割可能会产生较大的增益，并且浮点精度变得很重要。 另一个极端情况是，没有任何削减可以改善任何事情，或者最佳解决方案从未使用全部预算，但仍然无法准确达到预算。 

## 方法

 直接的方法是独立对待每个 cookie，并考虑是否切割它。 如果我们尝试切割饼干的所有子集，我们会计算总周长并检查它是否保持在范围内$P$。 这是正确的，但需要检查所有$2^N$子集，呈指数增长并立即中断$N=100$。 

相反，我们将问题重新表述为背包变体。 每个 cookie 贡献一个基础值$B_i = 2(W_i + H_i)$。 切割它会用新值替换它$C_i$，所以增益是$G_i = C_i - B_i$。 由于每个 cookie 最多可以在一个升级状态下使用，因此我们选择增益的子集，以在不超过预算的情况下最大化总增量$P - \sum B_i$。 

关键的结构见解是，尽管切割后的形状是不规则的，但所得的两个等面积块的周长仅取决于原始矩形尺寸，并且对于轴对齐的矩形，该值是固定函数。 因此，每个 cookie 都贡献了一个具有已知增益的独立“奖励选项”。 这将几何结构分解为纯粹的组合选择问题。 

现在任务变成：选择最多 100 个正增益值的子集，其总和尽可能大但不超过目标容量$K$。 自从$K$可以达到$10^8$，经典的 DP over sum 是不可能的。 然而，增益受到几何形状（源自矩形周长和对角线）的限制，并且它们的结构允许我们在移位范围内使用基于位集的子集和或排序后的贪婪+修剪方法，具体取决于精度处理。 

在实践中，我们计算所有增益，丢弃非正增益，对它们进行排序，并使用一个位集维护一组可实现的总和，其中索引表示可实现的额外周长。 然后我们发现最大可实现值不超过$K$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集 |$O(2^N)$|$O(N)$| 太慢了 |
 | 位集子集增益总和 |$O(N \cdot K / word)$|$O(K)$| 已接受 |

 ## 算法演练

 ## 1. 计算基础周长和剩余预算

 我们首先计算没有任何切割的总周长：$$B = \sum 2(W_i + H_i)$$那么剩余预算为：$$K = P - B$$这将问题转化为寻找可实现的最佳额外增益而不超过$K$。 

## 2. 计算切割每个矩形的增益

 对于每个矩形，我们在最佳单中心切割后计算周长。 这取决于将矩形分割成两个等面积形状的几何形状。 由此产生的周长是一个固定函数$W$和$H$，因此我们得出：$$G_i = C_i - B_i$$如果$G_i \le 0$，我们忽略它，因为它没有任何帮助。 

此步骤起作用的原因是每个 cookie 都是独立的，并且剪切决策不会影响任何其他 cookie。 

## 3. 构建增益的子集和状态

 我们维护一个位集`dp`在哪里`dp[s]`表明我们是否可以准确地获得额外的周长$s$。 最初，仅`dp[0] = True`。 

对于每一个增益$g$，我们更新：$$dp = dp \, \text{OR} \, (dp \ll g)$$这通过添加当前增益来转换所有先前可达到的总和。 

这是可行的，因为每个 cookie 最多可以使用一次，与 0/1 背包结构相匹配。 

## 4. 提取最佳可行答案

 我们扫描从$K$向下并选择最大的$s$这样`dp[s]`是真的。 最终的答案是$B + s$。 

反向扫描可确保我们在不超过限制的情况下最大化总周长。 

## 为什么它有效

 关键的不变量是在处理第一个之后$i$cookie，位集仅使用这些 cookie 精确编码所有可实现的增益和。 每次更新都会保留正确性，因为它会排除或包含当前 cookie 一次，以匹配问题约束。 由于每个配置对应于唯一的割集子集，并且每个子集都可以通过转换来表示，因此最终状态包含所有有效的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N, P = map(int, input().split())
        
        base = 0
        gains = []
        
        for _ in range(N):
            w, h = map(int, input().split())
            base += 2 * (w + h)
            
            # gain from optimal single center cut
            # splitting rectangle into two equal-area shapes increases perimeter
            # derived formula: +2 * sqrt(w^2 + h^2) - 2 * min(w, h)
            import math
            cut_perimeter = 2 * (w + h) + 2 * math.sqrt(w * w + h * h) - 2 * min(w, h)
            gain = cut_perimeter - 2 * (w + h)
            
            if gain > 1e-12:
                gains.append(gain)
        
        K = P - base
        if K <= 0:
            print(f"Case #{tc}: {base:.6f}")
            continue
        
        # scale to integers for stability
        scale = 1000000
        K = int(K * scale + 1e-9)
        int_gains = [int(g * scale + 1e-9) for g in gains]
        
        dp = 1
        for g in int_gains:
            dp |= (dp << g)
        
        best = 0
        while best <= K and (dp >> best) & 1:
            best += 1
        best -= 1
        
        ans = base + best / scale
        print(f"Case #{tc}: {ans:.6f}")

if __name__ == "__main__":
    solve()
```该实现首先累积基线周长，然后将问题转换为选择独立增益的子集。 浮点值缩放为整数以避免位组移位期间的精度漂移。 

位集`dp`存储为整数，利用 Python 的任意精度整数有效地模拟压缩位集。 移位与或更新对标准子集和转换进行编码。 

最后从 0 向上扫描找到不超过预算的最大可实现增益。

 ## 边缘情况

 一个关键的边缘情况是所有增益均为负或为零。 在这种情况下，DP 永远不会超出零，并且算法正确地返回基本周长不变。 

另一种情况是，即使存在剩余容量，最优解决方案也没有使用全部预算。 对可达总和的反向扫描确保我们选择最大的可行值，而无需强制精确饱和。 

最后，浮点不稳定性可能会导致增益排序不正确。 缩放步骤确保所有比较和 DP 转换都发生在整数空间中，从而保持测试用例之间的一致性。
