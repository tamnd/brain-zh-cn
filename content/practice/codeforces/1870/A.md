 ## 解决方案
 ## 问题理解

 我们正在构建一个长度的数组$n$使用非负整数，每个元素的上限为$x$。 该数组不是任意的：它必须有一个固定的 MEX 等于$k$，并且在所有此类有效数组中，我们想要元素总和最大的数组。 

MEX 条件强制采用非常具体的结构。 每个数字都来自$0$最多$k-1$必须至少出现一次，而该值$k$必须完全不存在。 一切大于$k$与 MEX 目的无关，只要不超过即可自由使用$x$。 

限制很小：$n, k, x \le 200$和$t \le 1000$。 这强烈表明每个测试用例必须在恒定或线性时间内解决。 每个测试用例的任何二次方都可以接受，但是任何涉及数组的排列或状态搜索的东西都是不必要的。 

第一个微妙的失败案例出现在以下情况：$k > x + 1$。 如果允许的最大值是$x$，那么我们甚至无法包含所有数字$0$到$k-1$。 例如，如果$x = 1$和$k = 3$，我们需要包括$0,1,2$， 但$2$是不可能放置的。 答案一定是$-1$。 

另一个失败案例来自于对 MEX 要求的误解。 例如，如果$k = 0$，我们不需要包含任何数字$0$到$k-1$（空集），但我们必须确保$0$数组中不存在。 这完全改变了最优结构，因为我们只能使用来自$1$到$x$。 

最后，一个天真的贪婪总是用$x$失败，因为它忽略了较小数字的强制存在$0$到$k-1$，这可能会迫使我们“浪费”原本可以最大化总和的头寸。 

## 方法

 暴力方法会尝试构造所有长度的数组$n$，每个条目$[0, x]$，然后计算 MEX 并跟踪最佳总和。 数组的数量是$(x+1)^n$，这甚至对于$n = 10$is already enormous. 这是完全不可行的。 

关键的观察结果是 MEX 约束仅限制两件事：所需的一组数字$0$通过$k-1$，以及一个禁止号码$k$。 其他的都是免费的优化空间。 

为了使总和最大化，每个未使用的位置都应该填充尽可能大的值，即$x$。 唯一的复杂之处是我们可能需要包含所需的数字$0$到$k-1$，这些可能不是总和的最佳选择，但它们是强制性的。 

我们还需要确保可行性。 准确获取 MEX$k$，我们必须包含所有数字$0$通过$k-1$，所以我们至少需要$k$职位。 这总是可能的，如果$n \ge k$，但是帽子$x$必须允许这些值。 

一旦确保了可行性，最佳策略就很简单：将每个$0,1,\dots,k-1$一次，用以下内容填充剩余位置$x$，并计算总和。 

还有一个额外的微妙之处：如果$k \le x$，我们必须确保我们不会不小心引入$k$，不过既然我们从来没有用过，这自然就满足了。

 | ---| ---| ---| ---|
 | 蛮力 |$O((x+1)^n)$|$O(n)$| 太慢了 |

 ## 算法演练

 我们现在直接构造答案。 

1. 首先，检查是否可以构建有效的 MEX。 如果$k > x + 1$，那么我们无法放置所有必需的值$0$到$k-1$因为$k-1 > x$。 在这种情况下，返回$-1$。 此条件捕获了由价值上限引起的所有不可能的情况。 
2. 计算所需元素的贡献$0,1,\dots,k-1$。 由于它们必须至少出现一次，因此我们将它们的总和相加$\frac{k(k-1)}{2}$。 这是执行 MEX 所需的最小结构$k$。 
3.填写剩余部分$n - k$具有最大允许值的位置$x$，因为用较小的数字替换其中任何一个都会严格减少总和，而不会影响 MEX 有效性。 
4、最终答案是：$$\text{sum} = \frac{k(k-1)}{2} + (n-k)\cdot x$$5. 如果$n < k$，我们也立即返回$-1$，因为我们无法放置所有必需的数字。 

### 为什么它有效

 该构造是最优的，因为 MEX 约束将数组完全解耦为两部分：不同所需值的强制前缀$0$到$k-1$，以及一个大小为的自由区域$n-k$。 强制部分在成员资格上没有灵活性，只有排列，排列不影响总和。 通过选择最大允许值来独立最大化空闲部分$x$。 由于位置之间不存在超出存在/不存在约束的交互，因此任何偏离此结构的行为要么违反 MEX，要么减少总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, x = map(int, input().split())

        # feasibility check
        if k > x + 1 or n < k:
            print(-1)
            continue

        # sum of required MEX prefix
        res = k * (k - 1) // 2

        # fill remaining with x
        res += (n - k) * x

        print(res)

if __name__ == "__main__":
    solve()
```实现直接反映了推理。 可行性检查确保我们能够真正实现 MEX$k$。 三角和计算强制包含$0$通过$k-1$。 剩下的位置都被贪婪地填满了$x$，这是安全的，因为它没有引入$k$并始终将贡献最大化。 

必须小心三角和中的整数除法，但 Python 可以干净地处理这个问题。 检查的顺序很重要：尽早失败可以避免对无效配置进行错误的算术。

 ## 边缘情况

 当$k = 0$，所需前缀为空。 该算法正确地将所需的总和设置为$0$并充满所有$n$职位与$x$, 给予$n \cdot x$。 这符合 MEX 要求，因为$0$缺席。 

什么时候$k = x + 1$，可行性条件仍然通过，并且构造完全使用所有值$0$通过$x$。 所需部分已无优化空间，但剩余位置仍可填补$x$。 

什么时候$n = k$，没有空闲职位。 答案就变成了$\frac{k(k-1)}{2}$，它对应于没有填充的强制 MEX 结构。
