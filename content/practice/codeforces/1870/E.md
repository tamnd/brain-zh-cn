 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并且可以将其分割成几个不相交的连续段，如果需要的话，可以留下一些未使用的元素。 对于每个选定的段，我们计算其 MEX，它是该段中缺失的最小非负整数。 然后我们获取所有这些 MEX 值并使用 XOR 将它们组合起来。 任务是在所有可能的选择段的方式上最大化最终的异或。 

重要的不仅仅是数组内的值，还包括小整数的出现次数如何分布，因为 MEX 完全取决于 0、1、2 等是否完全覆盖在段内。 每个分段独立地贡献一个整数值，但分段的选择决定了哪些值集可以足够“完整”以产生更大的 MEX 值。 

这些约束允许测试用例中最多有 5000 个总元素，这排除了每个测试用例中超过 n 的任何三次方。 每个测试用例的 O(n^2) 或 O(n log n) 左右的解决方案是可以接受的，但是任何枚举所有分段的解决方案都是不可行的，因为分区的数量呈指数增长。 

当假设每个段都可以独立优化时，就会出现天真的推理的微妙失败案例。 例如，采用最大化局部 MEX 的贪婪分段可以减少全局 XOR 的可能性。 当假设一旦一个段包含 0..k−1 时，扩展它总是最佳的，这会出现另一个失败，这是因为 XOR 依赖于组合多个中等大小的 MEX 值而不是单个大的值。 

## 方法

 暴力方法会尝试数组的每个可能的分区。 对于每个分区，计算每个段的 MEX 并将它们异或在一起。 这是正确的，但完全不可行，因为分区的数量以 n 为指数，大约为 2^(n−1)。 即使对于 n = 20，这也已经变得太大了。 

关键的见解是，尽管细分选择是全局性的，但我们可以生成的 MEX 值受到结构化方式的限制。 仅当段包含从 0 到 x−1 的所有整数时，它才会生成 MEX x。 这意味着每个段对应于收集一组所需的值，一旦数组中的这些值耗尽，我们就无法用大的 MEX 形成更多的段。 

我们没有直接推理分区，而是翻转视角：我们询问哪些 MEX 值可以独立实现以及如何组合它们。 因为 n ≤ 5000，我们可以为每个位置预先计算我们可以将段扩展多远以实现给定的 MEX 阈值，然后对具有 XOR 状态的前缀使用动态编程。 

我们将问题解释为选择不相交的间隔，每个间隔都标有由其 MEX 确定的值，并且我们在这些标签上最大化 XOR。 这成为经典的区间选择 DP，其中状态表示可达前缀的 XOR 值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 枚举所有分区 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | DP over 前缀 + MEX 间隔 | O(n^2·maxA) | O(n^2·maxA) | O(n·2^k) 优化 | 已接受 |

 ## 算法演练

 我们构建所有有效段及其 MEX 值，然后使用数组上的动态编程计算最佳 XOR 组合。

1. 预先计算每个值的下一个出现位置，以便我们可以快速测试一个段是否包含从 0 开始的所有数字。 
2. 对于每个起始索引 i，向右扩展一个段，同时跟踪出现了哪些小值。 我们维护一个布尔存在数组并增量计算当前段的 MEX。 
3. 每次我们将一个段从 i 延伸到 j 时，我们都会记录一个转换：从位置 j+1 开始，我们可以继续，并且我们可以选择对该段贡献异或，其值等于其 MEX。 
4. 定义一个 DP，其中 dp[i] 是使用从前缀 i 开始的有效段可实现的所有 XOR 值的位集。 
5. 我们从右到左处理位置。 对于每个 i，我们首先传播 dp[i+1]（跳过元素 i），然后尝试从 i 开始的所有段，并通过将 dp[j+1] 与 MEX(i, j) 进行异或来更新 dp[i]。 
6.答案是dp[0]最大异或状态。 

这种方法起作用的关键结构原因是，一旦我们修复了端点，段选择就是独立的：选择一个段会删除该间隔并在后缀上继续，因此问题变成了具有段权重异或组合的分区 DP。 

## 为什么它有效

 每个有效的构造都对应于将数组的子集划分为不相交的段。 每个部分贡献的价值仅取决于其内部内容。 DP 枚举每个位置处所有可能的第一段，并将它们与所有有效的后缀解决方案组合起来。 由于 XOR 具有关联性和可交换性，因此通过位集转换合并结果可以保持正确性，而不会出现重复计算或排序问题。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # We cap mex at n+1 because mex of any segment is <= n+1
        max_xor = 1 << 13
        dp = [set() for _ in range(n + 1)]
        dp[n].add(0)

        for i in range(n - 1, -1, -1):
            dp[i] = set(dp[i + 1])

            seen = [0] * (n + 2)
            mex = 0

            for j in range(i, n):
                seen[a[j]] = 1
                while seen[mex]:
                    mex += 1

                for val in dp[j + 1]:
                    dp[i].add(val ^ mex)

        print(max(dp[0]))

if __name__ == "__main__":
    solve()
```该代码从右到左构建 DP。 对于每个起始索引 i，它探索所有段 [i, j]，增量维护它们的 MEX，并将它们与所有可实现的后缀 XOR 状态组合。 跳过转换 dp[i] = dp[i+1] 确保我们可以保留未使用的元素，以匹配问题陈述。 

一个微妙的实现细节是增量 MEX 维护：为每个 j 从头开始​​重新计算 MEX 会太慢。 相反，我们维护一个频率数组并以每次扩展的摊销 O(1) 的方式更新 mex。 

## 工作示例

 考虑一个数组`[1, 0]`。 从索引 0 开始，段 [0,1] 具有 MEX 2，并且 dp[2] = {0}，因此 dp[0] 包括 2。还允许跳过元素，因此我们与较小的段进行比较，但最好是 2。 

| 我| j | 段 | 墨西哥 | DP 贡献 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | [1,0]| 2 | {2} |

 这显示了完整段如何直接产生最佳异或。 

现在考虑`[1,2,0,7,1,2,0]`。 存在多个细分； DP 探索所有分裂并累积 XOR 状态，确保捕获 (3,5) 或其他分解等组合。

 ## 边缘情况

 一个关键的边缘情况是数组不包含零。 在这种情况下，每个段都有 MEX 0，因此无论分区如何，XOR 都保持为 0，并且 DP 只正确传播零状态。 另一个边缘情况是当所有元素都为零时，每个段都有 MEX 1，因此最佳策略取决于选择段计数的奇偶校验； DP 自然地探索偶数和奇数分割并捕获正确的 XOR。
