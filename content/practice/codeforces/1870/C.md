 ## 解决方案
 ## 问题理解

 我们得到一个数组`a`长度`n`之间的整数`1`和`k`。 从`a`，我们定义一个方桌`b`尺寸的`n × n`其中每个单元格`(i, j)`是最小值`a[i]`和`a[j]`。 中的每个整数`b`代表一种“颜色”。 任务是，对于每一种颜色`1`到`k`，找到最小的矩形`b`包含该颜色的所有单元格并报告矩形的宽度和高度之和。 

问题约束表明两者`n`和`k`可以大到`10^5`，但是所有的总和`n`和`k`跨测试用例仅限于`10^5`。 一种暴力方法，构建`n × n`桌子`b`明确要求最多`10^10`在最坏的情况下进行操作，这显然是不可能的。 我们必须利用结构`b`无需构建完整表格即可计算结果。 

一个关键的观察结果是`b[i][j]`总是以上界为`a[i]`和`a[j]`。 这意味着较高值的“矩形”包含在由元素位置定义的区域中`a`至少是那个值。 不明显的边缘情况包括某些颜色完全丢失的数组，或者某种颜色仅出现一次的数组。 例如，如果`a = [3, 2, 4]`和`k = 5`， 颜色`1`和`5`失踪于`a`。 这些颜色的正确边数是`0`。 幼稚的方法可能会错误地尝试使用不存在的单元格来查找矩形。 

## 方法

 蛮力解决方案将明确构造`n × n`桌子`b`并且，对于每种颜色，扫描每个单元格以查找该颜色出现的最小和最大行索引和列索引。 矩形的宽度是`(max_col - min_col + 1)`高度是`(max_row - min_row + 1)`。 该方法的时间复杂度为`O(k * n^2)`，鉴于`n`可以是`10^5`。 内存使用也是一个问题，因为`b`需要`O(n^2)`空间。 

关键的见解是`b[i][j] = min(a[i], a[j])`仅取决于元素的位置`a`至少是给定的颜色。 如果我们想要矩形的颜色`c`，我们只需要知道数字 ≥ 的第一次和最后一次出现`c`在`a`。 形式上，如果我们维护元素的最左边和最右边的索引`a`是 ≥`c`，我们可以计算覆盖所有颜色出现的矩形`c`无需构建`b`。 矩形的宽度和高度分别由元素索引之间的最大距离确定 ≥`c`。 通过迭代`c`从`k`下降到`1`并传播索引，我们避免重复扫描`a`对于每种颜色。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(k * n^2) | O(k * n^2) | O(n^2) | O(n^2) | 太慢了 |
 | 最佳 | 每个测试用例 O(n + k) | O(k) | 已接受 |

 ## 算法演练

 1. 初始化数组`left[c]`和`right[c]`跟踪最小和最大的索引`a`其中一个元素至少是`c`。 放`left[c] = n`和`right[c] = -1`作为初始哨兵值。 
2. 迭代`a`从左到右。 对于每个位置`i`有价值`a[i]`， 更新`left[v]`和`right[v]`为所有人`v ≤ a[i]`。 这确保了`left[v]`捕获元素 ≥ 的最早索引`v`发生，并且`right[v]`捕获最新的。 稍后我们按颜色降序传播最小和最大索引，以填补缺失数字的空白。 
3.处理完所有位置后，迭代自`k`下降到`1`。 对于每种颜色`c`， 更新`left[c] = min(left[c], left[c + 1])`和`right[c] = max(right[c], right[c + 1])`考虑到可能没有明确出现的颜色`a`但隐含地被更高的值覆盖。 
4. 对于每种颜色`c`， 如果`left[c] > right[c]`，这意味着颜色缺失`a`，所以矩形和是`0`。 否则，将矩形边计算为`width = right[c] - left[c] + 1`和`height = width`因为`b`是对称的，并且矩形在索引空间中是正方形。 宽度和高度之和为`2 * width`。 
5. 输出所有颜色的结果`1`到`k`。 

为什么它有效：该算法正确识别了索引的范围`a`对每种颜色都有贡献。 中的矩形`b`对于一种颜色`c`始终从最左边的索引跨越到最右边的索引，其中`a[i] ≥ c`，水平和垂直。 从较高颜色传播索引可确保不会丢失任何颜色，并且使用哨兵值可避免缺失颜色的错误。 的对称性`b`保证宽度和高度由相同的索引范围确定。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        left = [n] * (k + 2)
        right = [-1] * (k + 2)
        
        for i, val in enumerate(a):
            left[val] = min(left[val], i)
            right[val] = max(right[val], i)
        
        # propagate from higher to lower colors
        for c in range(k, 0, -1):
            left[c] = min(left[c], left[c + 1])
            right[c] = max(right[c], right[c + 1])
        
        res = []
        for c in range(1, k + 1):
            if left[c] > right[c]:
                res.append(0)
            else:
                width = right[c] - left[c] + 1
                res.append(2 * width)
        print(*res)

solve()
```代码中的每个部分都直接映射到算法。 正在初始化`left`和`right`避免单独处理缺失的颜色。 迭代时更新索引`a`确保线性时间处理。 传播自`k`down 处理缺失的中间颜色，并进行计算`2 * width`由于对称性，给出正确的边和`b`。
