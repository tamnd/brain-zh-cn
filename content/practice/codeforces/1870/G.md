 ## 解决方案
 ## 问题理解

 给定一个数组，我们逐一查看它的前缀。 对于每个前缀，我们将其视为整数多重集，并想象重复执行一个非常不寻常的操作：我们选择任何非空子多重集，将其删除，计算其 MEX，并将该 MEX 插入回来。 我们可以任意重复此操作多次。 最终，我们被迫陷入一种只剩下一个数字的情况，我们想知道这个最终数字可能的最大值。 

关键的困难在于该操作不保留大小，并且可能会破坏或创建较小的数字。 由于我们可以自由选择子集，因此该过程不是确定性的，并且我们正在优化所有可能的操作序列。 

每个前缀独立地提出相同的问题：给定前 i 个元素，可实现的最大最终值是多少。 

约束很严格：测试用例的总长度为 2e5，因此我们需要每个测试本质上是线性或接近线性的行为。 任何涉及显式模拟操作或子集推理的事情都是立即不可能的。 

一个天真的错误是假设贪婪的本地 MEX 行为就足够了。 例如，认为我们总是组合所有内容或总是独立提取最小缺失值的想法是失败的，因为操作可以以非平凡的方式跨步骤交互。 

一个更微妙的陷阱是假设答案只是最大前缀 MEX 或最大元素。 小例子已经打破了这两种直觉：MEX 操作可以产生比最初存在的任何值都大的新值，同时还允许重复重组，从而消耗小数字的重复项。 

## 方法

 强力解释将尝试模拟所有可达的多重集或所有可能的子集删除序列。 即使我们将状态编码为频率向量，每个操作都可以选择任何子集，并且子集的数量与前缀的大小呈指数关系。 分支因子实际上是每步 2^n，因此即使 n = 30，这也是完全不可行的。 

关键的结构见解是停止思考任意子集，而是了解重复的 MEX 转换最终可以产生什么值。 

该操作从根本上让我们可以用一组值“交易”单个 MEX 值。 重要的观察是，只有小整数的存在或不存在才重要。 一旦我们有了足够的数字副本，我们就可以以受控的方式重复使用 0、1、2……的出现。 

只要我们有足够的所有较小整数的“供应”，该变换的行为就像一个可以生成新整数的系统。 为了产生值 x 作为最终结果，我们必须能够在过程中的某个时刻创建从 0 到 x-1 的所有整数。 这表明问题简化为跟踪我们可以完成缺失值“链”的次数。 

查看该过程的一个有用方法是，每次我们想要生成一个新数字时，我们都需要在某些操作序列中“花费”所有较小数字的出现至少一次。 这导致了贪婪的累积条件：我们跟踪计数并确定我们可以维持多少个完整的 0、1、2…层。 

我们不是模拟操作，而是维护频率并增量计算前缀可以支持完整连续构造的程度。 每个前缀都扩展了可用的供应，并且只有当我们可以扩展可到达的连续段时，答案才会增长。 

这将问题变成了维护有多少完整的“MEX 结构”是可能的，并且可以在线更新。

 ## 算法演练

 我们从左到右处理数组，同时维护频率计数和一个描述我们已经可以保证在结构化意义上“可用”的连续小整数的指针。 

1. 维护频率数组`cnt[x]`对于迄今为止看到的值。 这告诉我们当前每个整数的供应是否足够。 
2. 维护一个变量`need`，表示最小整数，因此我们尚不能完全支持在 MEX 构造意义上构建它。 最初`need = 0`。 
3. 阅读每个新元素后`a[i]`，增加其频率。 
4.努力前进`need`尽可能：同时`cnt[need] > 0`，我们可以处理一次出现`need`作为完整“链”的一部分，能够构建更大的价值，因此我们增加`need`。 

The reasoning is that as long as every integer below`need`至少以可用的方式出现过一次，我们可以模拟构建解锁更高值的 MEX 层的过程。 
5. 当前前缀的答案是`need`。 

这种贪婪扩展捕获可以“消耗”到重复 MEX 操作中的最大连续整数段，而该段长度正是决定可以构造的最终值有多大。 

### 为什么它有效

 关键的不变量是，处理完一个前缀后，所有整数`[0, need-1]`保证可以通过某些操作序列产生，同时`need`尚未完全支持。 

每当我们观察到新的情况发生时`need`，它消除了阻碍施工的障碍`need`，因为它有助于完成较小的 MEX 建设步骤的必要链。 由于 MEX 始终仅依赖于缺失的最小值，因此该过程可以线性化为扩展第一个缺失的整数边界。 如果不先填充所有较小的值，则任何操作都无法跳过此边界，因此`need`单调前进并且永远不会超过真正可实现的最大最终值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    MAXV = 200000 + 5

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        cnt = [0] * (n + 5)
        need = 0
        res = []

        for x in a:
            if x < len(cnt):
                cnt[x] += 1

            while need < len(cnt) and cnt[need] > 0:
                need += 1

            res.append(str(need))

        print(" ".join(res))

if __name__ == "__main__":
    solve()
```该代码维护前缀的频率表和单个指针`need`跟踪尚未“完全支持”的最小整数。 每次插入后，它都会尽可能地贪婪地前进该指针。 每个前缀后面的结果正是 this 指针。 

一个微妙的点是`need`永远不会减少，因此整个运行过程中所有 while 循环的总成本在最大值范围内呈线性。

 ## 边缘情况

 一种重要的边缘情况是数组仅包含大量数字。 在这种情况下，不会出现任何小整数，所以`need`所有前缀都保持为 0，这与无法启动基于 MEX 的构造这一事实相匹配。 

另一种情况是重复零。 天真的解释可能会认为多个零有帮助，但只有每个整数的存在对于推进构造边界很重要。 

最后一个微妙的情况是值出现较晚。 例如，在几个大数之后突然遇到 0 允许该过程开始，并且`need`一旦存在足够的连续值，就会相应地跳转。
