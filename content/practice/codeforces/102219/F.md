 ## 解决方案
 ## 问题理解

 我们有两排（n）名士兵。 匹配从第二行中为第一行中的每个士兵恰好选择一个士兵，并且每个第二行士兵恰好使用一次。 所以答案是 (1,\ldots,n) 的有效排列 (p) 的数量，使得第一行中的士兵 (i) 与第二行中的士兵 (p_i) 匹配 (|i-p_i|\le e)，并且不使用任何明确禁止的对 ((u_i,v_i))。 

有趣的限制不仅仅是 (e) 很小。 它表示每个士兵（i）只能在短间隔（[i-e，i+e]）内与第二排位置互动。 由于 (e\le4)，任何第一排士兵最多有 (9) 个相关的第二排位置。 第一排士兵的数量可以达到（2000），因此需要多项式算法。 (O(n^2)) 算法已经有大约四百万个基本操作，这是合理的，而 (n) 中的任何指数都是不可能的。 小常数 (e) 是让我们保持指数状态空间的特征，其大小取决于 (e)，而不是 (n)。 

幼稚的实现也可能在边界处失败。 例如，与```
1 0 0
```正好有一个匹配，所以答案是（1）。 盲目假设位置 (i-e,\ldots,i+e) 都存在的 DP 可能会意外地将不存在的第二排士兵视为可用。 

另一个边界情况是```
2 1 0
```其答案是（2）。 两种匹配都是可能的：(1\to1,2\to2) 和 (1\to2,2\to1)。 当窗口移过右端时，粗心的滑动窗口实现可能会丢失这些状态之一。 

仅当处理相应的第一排士兵时才必须应用禁止对。 例如，```
2 1 1
1 2
```答案为 (1)，因为匹配 (1\to2,2\to1) 被禁止，而 (1\to1,2\to2) 仍然有效。 如果禁止对被全局存储而没有将其连接到DP的正确行，则很容易删除错误的转换。 

情况(e=0)在结构上也不同。 和```
3 0 0
```答案是（1），因为每个士兵都有一个可能的伙伴。 假设至少两个候选位置的状态转换实现可能会引入无效转换或错误处理一位掩码。 

## 方法

 最直接的暴力解决方案是一次构建匹配的第一排士兵。 对于士兵(i)，它会尝试满足(|i-j|\le e)的每个第二排士兵(j)，检查(j)是否已经被使用，并继续递归。 当所有（n）个士兵都被处理后，就找到了一个完整的匹配。 

这是正确的，因为每个可能的匹配都对应于一个选择序列，并且当选择违反距离限制、禁止对或每个第二排士兵都使用一次的要求时，递归会精确地拒绝该选择。 

问题在于探索的状态数量。 尽管每个士兵最多有 (2e+1\le9) 个候选者，但递归搜索的指数上限为 (9^n)。 对于 (n=2000)，该界限为 (9^{2000})，大约为 (10^{1908})，远远超出任何实际操作数量。 生成所有 (n!) 个排列的更简单的暴力方法将执行大约 (n\cdot n!) 对检查，这甚至更糟糕。 

蛮力之所以有效，是因为士兵的合法伙伴是本地人，但它会反复重新计算相同的部分情况。 假设我们已经处理了士兵 (1,\ldots,i-1)。 对于未来的士兵来说，我们不需要记住使用了哪些第二排士兵的完整历史。 我们只需要知道当前局部区间中哪些位置被占用即可。 

关键的观察是，未来的第一排士兵永远不能使用其后面超过 (e) 个位置的第二排位置。 一旦我们从士兵（i）移动到士兵（i+1），当前窗口中最左边的位置将永久离开窗口。 应该是已经匹配过了。 同时，只有一个新位置进入窗口。 

这给出了滑动窗口位掩码 DP。 窗口有(2e+1)个位置，最多有(9)个，所以最多有

 [
 2^{2e+1}\le2^9=512
 ]

 可能的状态。 我们处理所有 (n) 个第一排士兵，并且对于每个状态最多尝试 (2e+1\le9) 个候选伙伴。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 修剪搜索中的 (O((2e+1)^n)) | (O(n)) 递归深度 | 太慢了 |
 | 最佳| (O(n(2e+1)2^{2e+1})) | (O(2^{2e+1}+k+n)) | 已接受 |

 ## 算法演练

 1.围绕当前第一排士兵(i)定义一个(2e+1)个第二排位置的滑动窗口。 位(b)代表位置

 [
 j=i-e+b。 
]

 等于 (1) 的位意味着该位置已经不可用，要么是因为它之前已经匹配过，要么是因为它位于实际范围 (1,\ldots,n) 之外。 将数组外部的位置视为已占用，可以让相同的转换逻辑在数组的两端工作。 

1. 在处理士兵(1)之前，构建窗口的初始掩模

 [
 1-e,\l点,1+e。 
]

 (1) 以下的每个位置都标记为已占用。 每个真实位置最初都是空闲的，除非它已经被问题排除，尽管禁止对被处理为转换限制而不是最初占用的位置。 

1. 对于每个第一排士兵 (i)，构造一个位掩码`allowed`包含当前窗口中不禁止 (1\le j\le n)、(|i-j|\le e) 和 ((i,j)) 的位置 (j)。 
2. 对于每个可达的 DP mask，找到可用的候选位置

 [
 \text{选择}=\text{允许}\ &\ \sim\text{掩码}。 
]

 每个设定位`choices`代表士兵（i）的一个可能的伙伴。 选择该位对应于为当前状态表示的每个部分匹配创建一个可能的扩展。 

1. 选择合作伙伴后，检查生成的掩码的最左边位。 最左边的位置是(i-e)。 士兵 (i) 匹配后，未来的第一排士兵将无法使用该位置。 因此，如果该位仍然为零，则部分匹配永远无法完成并且必须被丢弃。 

这是滑动窗口 DP 的核心有效性检查。 它可以防止我们将比赛推迟到最后一个可以合法使用特定第二排位置的第一排士兵之后。 

1. 将掩码向右移动一位。 旧位置（i-e）消失，每个剩余位置向左移动一位，新位置（i+e+1）进入最高位。 

如果新位置大于(n)，则它在真正的第二行之外，因此其位被插入为(1)。 否则它会被插入为 (0)，因为没有早期的士兵可以使用这个新引入的位置。 

1. 将结果掩码的部分匹配数存储在下一个 DP 数组中。 所有加法均以模 (10^9+7) 执行。 
2.处理完所有(n)个第一排士兵后，唯一有效的最终状态是全1掩码。 每个真实的第二行位置都必须已被使用，而 (1,\ldots,n) 之外的每个位置也被标记为已占用。 该状态的值就是所需的答案。 

### 为什么它有效

 处理第一排士兵 (1,\ldots,i) 后，DP 不变量为`dp[mask]`精确计算当前窗口内已使用和不可用的第二行位置描述为的那些士兵的部分匹配`mask`。 已经离开窗口的位置不再需要，并且转换明确要求在丢弃之前占用离开的位置。 每个合法伙伴都由一个空闲允许位表示，因此每个有效的部分匹配都恰好具有由转换表示的可能延续，没有重复。 最后，全1状态意味着每个真正的第二排士兵都被恰好匹配过一次，因此它的计数正是完整有效匹配的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    n, e, k = map(int, input().split())

    # bad[i] is a bitmask of second-row positions forbidden for first-row i.
    bad = [0] * (n + 1)

    for _ in range(k):
        u, v = map(int, input().split())
        # v is relevant only if it can be within e of u.
        d = v - (u - e)
        if 0 <= d <= 2 * e:
            bad[u] |= 1 << d

    width = 2 * e + 1
    states = 1 << width
    top_bit = 1 << (width - 1)
    full = states - 1

    # For every first-row position, build the set of legal real
    # second-row positions in its current window.
    allowed = [0] * (n + 1)

    for i in range(1, n + 1):
        mask = 0
        base = i - e
        for b in range(width):
            j = base + b
            if 1 <= j <= n and not (bad[i] >> b & 1):
                mask |= 1 << b
        allowed[i] = mask

    # Initial window for i = 1 is [1-e, 1+e].
    # Positions <= 0 are outside the array, so mark them occupied.
    start_mask = 0
    base = 1 - e
    for b in range(width):
        j = base + b
        if j < 1 or j > n:
            start_mask |= 1 << b

    dp = [0] * states
    dp[start_mask] = 1

    for i in range(1, n + 1):
        cur_allowed = allowed[i]
        out_of_range = i + e + 1 > n

        ndp = [0] * states

        for mask, ways in enumerate(dp):
            if ways == 0:
                continue

            choices = cur_allowed & ~mask

            while choices:
                bit = choices & -choices
                choices -= bit

                used = mask | bit

                # The position leaving the window must already be used.
                if (used & 1) == 0:
                    continue

                new_mask = used >> 1

                # Introduce position i+e+1.
                if out_of_range:
                    new_mask |= top_bit

                ndp[new_mask] = (ndp[new_mask] + ways) % MOD

        dp = ndp

    print(dp[full] % MOD)

if __name__ == "__main__":
    solve()
```这`bad`数组将禁止的第二行位置存储为本地位。 对于禁止对((u,v))，位位置是(v-(u-e))，因为(u)行窗口的位(0)代表(u-e)。 这使得禁止边检查保持恒定的时间。 

这`allowed`数组是预先计算的，因此主 DP 循环不会重复测试距离条件或搜索禁止对结构。 由于每个窗口最多包含 9 个位置，因此构造所有这些掩模的成本仅为 (O(ne))。 

初始掩模需要特殊处理，因为第一个窗口延伸到小于（1）的位置。 这些位置无法选择，因此它们的位以 (1) 开头。 当新位置从右侧进入时，使用相同的想法：一旦(i+e+1>n)，新位被插入为(1)。 

表达式`choices = cur_allowed & ~mask`隔离尚未使用的每个法律位置。 循环`bit = choices & -choices`一次提取一个候选者，而无需再次扫描所有九位。 

添加新选择的伙伴后必须进行传出位检查。 如果传出位为零，则当前士兵无法匹配即将变得无法到达的第二排位置。 这种状态无法导致完全匹配。 

Python 整数不会溢出，但每次加法后 DP 值仍会按模 (10^9+7) 减少。 使用两个数组而不是保留所有 (n) 层，因为只需要前一层。 

## 工作示例

 ### 示例 1

 输入是```
2 1 0
```这里窗口有三个位置。 对于第一个士兵，窗口是（0,1,2），因此位置（0）开始被占据。 每一步之后，(1,2) 之外的位置也被标记为已占用。 

| 第一排士兵 (i) | 当前掩码| 选择的合作伙伴 | 新面膜|
 | ---| ---| ---| ---|
 | 1 |`001`| 1 |`101`|
 | 1 |`001`| 2 |`110`|
 | 2 |`101`| 2 |`111`|
 | 2 |`110`| 1 |`111`|

 两条路径分别对应(1\to1,2\to2)和(1\to2,2\to1)。 两者都以全 1 状态结束，因此答案是 (2)。 

该跟踪显示了为什么掩码必须包含实际数组之外的位置。 如果不将位置(0)和(n)之外的位置标记为已占用，则最终状态将不能准确地表示所有真实的第二行位置都已被消耗。 

### 示例 2

 输入是```
2 1 1
1 2
```(1\to2) 对 (1\to2) 是禁止的，因此第一个士兵只有一次合法的转换。 

| 第一排士兵 (i) | 当前掩码| 允许的选择 | 选择的合作伙伴 | 新面膜|
 | ---| ---| ---| ---| ---|
 | 1 |`001`| 1 | 1 |`101`|
 | 2 |`101`| 2 | 2 |`111`|

 唯一幸存的匹配是 (1\to1,2\to2)，所以答案是 (1)。 

该迹线表明禁止对不需要新的 DP 维度。 他们只是从相应第一排士兵可用的转换集中删除一位。
