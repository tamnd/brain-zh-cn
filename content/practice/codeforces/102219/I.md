 ## 解决方案
 ## 问题理解

 道路由 3 x 10 字符网格表示。 RoboTaxi 占据标记的单元格`=`，并且只能沿着当前行继续直线。 其余单元格为空，表示为`.`，或代表的障碍物`H`,`T`， 和`P`。 

由于出租车从不变道或反转方向，因此只有严格位于右侧的单元格`=`位于同一行会影响结果。 在这些牢房中，遇到的第一个障碍就是出租车撞上的障碍物。 如果前面的每个单元格都是空的，则出租车到达给定快照的末尾而不会崩溃，因此所需的输出是`You shall pass!!!`。 

尺寸是固定的：正好有 3 行和正好 10 列。 即使对每个单元进行直接扫描也仅执行 30 个字符检查，这在 1 秒时间限制和 256 MB 内存限制下可以忽略不计。 不存在可能使二次甚至线性扫描出现问题的大输入参数。 这里有用的优化并不是性能所必需的，但它使问题的结构变得明确：一旦知道出租车的行，其他两行就无关紧要了。 

一个常见的边缘情况是出租车可能位于第一列。 例如：```
=.........
..........
..........
```正确的输出是`You shall pass!!!`。 找到出租车后从第 1 列而不是第 0 列开始检查的粗心实现可以正确处理这种特殊情况，但假设出租车之前必须至少有一个单元格的代码很容易引入无效索引或完全跳过扫描。 

另一个边缘情况是出租车旁边的障碍物：```
..........
=P........
..........
```答案是`P`。 必须从下一列开始检查障碍物。 开始扫描前方两个位置会错误地报告出租车经过。 

当同一车道上出现多个障碍物时，第一个障碍物也很重要：```
..........
=..H..TP..
..........
```正确的输出是`H`。 出租车在到达第一个障碍物时就坠毁了，所以后来`T`和`P`细胞绝不能取代先前的答案。 

最后，必须忽略其他车道上的障碍物。 例如：```
..H.......
=.........
.......T..
```答案是`You shall pass!!!`。 扫描整个网格以查找任何`H`,`T`， 或者`P`如果不首先将搜索限制在出租车所在行，将会产生错误的结果。 

## 方法

 暴力解决方案可以检查所有 30 个单元格，找到`=`，然后检查该行右侧的道路单元格。 它的正确性直接来自于移动规则：出租车只能访问自己所在行的单元格，并且从左到右访问它们。 在最坏的情况下，最多执行 30 次检查，然后沿出租车行最多执行 10 次检查。 对于这个固定的输入大小来说，最多有 40 个恒定时间操作，所以它已经相当快了。 

对于上述问题，这种蛮力方法不会变得太慢，因为道路尺寸永远不会增长。 如果同样的想法推广到一条道路`n`列，扫描整个网格将花费`O(n)`对于固定的行数，只扫描出租车的行也需要`O(n)`。 这里的区别主要是概念性的，而不是性能关键的。 

关键的观察是，一旦我们知道包含以下内容的行，出租车的未来路径就完全确定了`=`。 另外两排不会影响碰撞，出租车左侧的单元格已经通过。 我们可以定位`=`然后仅沿着该行向前扫描。 其中第一个字符`H`,`T`， 和`P`立即就是答案。 

因此，最简单接受的实现也是最直接的：找到出租车，向右走，并在第一个障碍物处停下来。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(30)，实际上是 O(1) | O(1) | O(1) | 已接受 |
 | 最佳 | O(10)，实际上是 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将道路的三行读入数组。 我们保留网格是因为事先不知道出租车的排号。 
2. 在三行中搜索该字符`=`并记录其行和列。 仅有一个出租车位置，因此这唯一地决定了重要的路径。 
3. 从出租车后面的一列开始，逐一检查单元格，同时保持在同一行。 扫描开始于`taxi_column + 1`因为出租车自己的小区不再是障碍物，而且它之前的小区也无法到达。 
4. 如果当前单元格是`H`,`T`， 或者`P`，打印该字符并停止。 由于扫描从左向右移动，这必然是出租车遇到的第一个障碍。 
5. 如果扫描到第 9 列而没有发现障碍物，则打印`You shall pass!!!`。 此时，快照中的每个可到达的单元格都已被检查并且为空。 

### 为什么它有效

 中心不变量是在检查列之前`c`，出租车原始位置和列之间的每个可到达的单元格`c - 1`已经检查完毕，没有障碍物。 出租车仅在其原始行中向右移动，因此该序列之外的任何未检查的单元格都不会导致较早的碰撞。 当扫描发现障碍物时，不变量证明在其之前没有障碍物发生，使该角色成为第一个崩溃的角色。 如果扫描完成后没有找到，则出租车剩余路径中的每个单元格都是空的，因此出租车不会在快照内崩溃。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    grid = [input().strip() for _ in range(3)]

    taxi_row = -1
    taxi_col = -1

    for r in range(3):
        for c in range(10):
            if grid[r][c] == '=':
                taxi_row = r
                taxi_col = c
                break
        if taxi_row != -1:
            break

    for c in range(taxi_col + 1, 10):
        if grid[taxi_row][c] in "HTP":
            print(grid[taxi_row][c])
            return

    print("You shall pass!!!")

if __name__ == "__main__":
    solve()
```输入部分正好读取三行，与固定的道路尺寸相匹配。`strip()`删除换行符而不更改任何有意义的道路字符。 

嵌套搜索发现`=`并存储其行和列。 第二个`break`这是必要的，因为找到出租车会结束所有行的搜索，而不仅仅是当前行。 

碰撞扫描开始于`taxi_col + 1`。 该边界是实现中最重要的索引细节。 出租车自己的小区是`=`，因此检查它永远不会发现障碍物，但从错误的后面一列开始可能会跳过出租车前面的障碍物。 

会员资格测试`in "HTP"`识别所有三个可能的障碍，而不需要三个单独的比较。 一旦找到，就会打印该字符并且函数返回，保留报告第一个障碍而不是最后一个障碍的要求。 

不使用涉及大值的整数运算，因此不会发生溢出。 网格本身仅包含 30 个字符，因此内存使用量实际上保持不变。

 ## 边缘情况

 当出租车已经停在最后一列时，前面就没有可以检查的单元格了。 例如：```
..........
.........=
..........
```该算法发现`taxi_col = 9`并从第 10 列开始扫描。由于范围为空，因此它立即打印`You shall pass!!!`。 这可以避免越界访问，并正确模拟出租车在快照内没有剩余道路的事实。 

当前方有障碍物时，扫描必须包括该相邻单元格。 为了：```
..........
=P........
..........
```出租车位于第 0 列，因此扫描从第 1 列开始。该单元格包含`P`，算法立即打印`P`。 以后的障碍没有机会覆盖答案。 

当多个障碍依次出现时，第一个障碍决定结果。 为了：```
..........
=..H..TP..
..........
```扫描检查第 1 列和第 2 列，然后到达`H`在第 3 列。它打印`H`并在到达之前返回`T`或者`P`。 从左到右的扫描顺序直接强制执行所需的冲突顺序。 

当其他车道有障碍物时，它们不起作用。 考虑：```
H.........
=.........
........P.
```出租车在中间一排，后面的每个单元格`=`该行是空的。 这`H`和`P`属于不同的行，因此在冲突扫描期间不会检查它们。 结果是`You shall pass!!!`。 

道路的尺寸是固定的，因此最小的有意义的情况仍然是所需的 3 x 10 网格。 畅通无阻的道路，例如：```
..........
..........
=.........
```出租车的路径上没有障碍物。 该算法将出租车定位在底行，检查前面的所有九个单元格，然后打印`You shall pass!!!`。 

最终的边界情况是第 9 列中的障碍物，即最后可到达的位置：```
..........
=........H
..........
```检查每个前面的单元格并检测到后，扫描到达第 9 列`H`。 这会捕获常见的差一错误，即循环意外停止在第 8 列而不是包括最后一列。
