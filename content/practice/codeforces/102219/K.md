 ## 解决方案
 ## 问题理解

 每个客户请求都有一个处理时间`t`。 如果尼娜从时间开始`0`，该请求必须按时间完全处理`2t`为了让客户满意。 Nina 可以选择处理请求的顺序，并且她希望最大限度地增加满足截止日期的请求数量。 

输入包含最多 20 个独立测试用例。 对于每种情况，`n`可以大到`10^5`，而每个处理时间可以大到`10^9`。 答案是在各自的截止日期之前可以完成的最大请求数。 自从`n`达到`10^5`，枚举子集或排列是不可能的。 我们周围需要一些东西`O(n log n)`或根据具体情况更好。 一秒的时间限制也使得二次方法不适合最大的情况。 

第一个结构观察是具有处理时间的请求`t`有截止日期`2t`。 因此，它的处理时间和截止日期都是由相同的值决定的。 如果两个请求有处理时间`a <= b`，那么他们的截止日期也满足`2a <= 2b`。 因此，按处理时间对请求进行排序也会对它们的截止日期进行排序。 

例如，使用输入`1 / 1`，单个请求总是可以满足的，因为它在某个时间完成`1`，这最多是它的截止日期`2`。 一个粗心的实现，检查是否`t <= 0`或将截止日期视为`t`会错误地拒绝它。 

考虑`1 / 3 / 1 1 1`。 正确答案是`2`。 完成前两个请求后，当前时间为`2`，这正是第二个请求的截止日期。 第三个请求将在时间完成`3`，在截止日期之后`2`。 一个实现使用`<`而不是`<=`会错误地拒绝第二个请求并返回`1`。 

一个更有趣的案例是`1 / 4 / 1 1 1 3`。 前两次请求后，累计时间为`2`。 第三个请求无法在截止日期前完成，因为`2 + 1 > 2`，所以必须跳过。 长度要求`3`然后可以在某个时间完成`5`，恰好在截止日期之前`6`。 正确答案是`3`。 一个常见的错误是在第一次失败的请求后停止，而不是在更晚的期限内继续检查。 

最后，大值需要将累积处理时间存储在足够宽的整数类型中。 和`10^5`要求每次采取`10^9`，总和可以达到`10^14`。 Python 整数会自动处理此问题，但另一种语言的固定宽度实现将需要 64 位整数。 

## 方法

 直接的暴力解决方案可以考虑请求的每个子集，按处理时间对该子集进行排序，并检查每个选定的请求是否在截止日期之前完成。 这是正确的，因为满意客户的每一种可能选择都由一个子集表示，并且通过增加截止日期对所选子集进行排序给出了正确的可行性顺序。 有`2^n`子集，并且检查一个子集可以花费`O(n)`时间、给予`Theta(n 2^n)`以简单的实施方式工作。 即使仅子集的数量也已经不可能`n = 10^5`。 

有用的结构来自这样一个事实：截止日期恰好是处理时间的两倍。 对所有请求进行排序`t`。 假设当前选择的请求有总处理时间`S`，并且下一个请求有处理时间`t`。 如果我们添加它，它的完成时间是`S + t`。 其截止日期是`2t`，所以接受的条件就变成了`S + t <= 2t`这简化为`S <= t`。 

这非常方便。 排序后，未来每个请求的处理时间至少与当前请求一样长。 如果当前的请求无法满足，保留它无法帮助我们达到更多满足的请求。 这是迄今为止考虑的最大请求，因此用它替换任何已选择的请求只会增加总处理时间。 

暴力解决方案之所以有效，是因为它明确地考虑了每个可能的子集，但由于子集的数量呈指数级增长，因此会失败。 观察到请求可以按递增顺序处理，并且当当前累积时间至多是其自己的处理时间时，请求完全适合，这让我们可以独立地为每个请求做出贪婪决策。 

贪心规则很简单：对值进行排序，从小到大扫描它们，并在当前累积时间最多为该请求的值时添加请求。 否则跳过它并继续。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(n 2^n)`|`O(n)`| 太慢了 |
 | 最佳 |`O(n log n)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 按非降序对所有请求处理时间进行排序。 这也对他们的截止日期进行了排序，因为有价值的请求`t`有截止日期`2t`。 按此顺序处理选定的请求足以检查可行性。 
2. 设置`total = 0`和`answer = 0`。 这里`total`代表我们决定满足的请求已经花费的时间。 
3. 对于每个已排序的请求以及处理时间`t`，检查是否`total <= t`。 这正是截止日期条件，因为接受请求将使其完成时间`total + t`，而其截止日期是`2t`。 
4. 如果`total <= t`，接受请求。 增加`total`经过`t`并增加`answer`一个。 现在保证请求不迟于`2t`。 
5.如果`total > t`，跳过请求。 由于之前考虑的所有请求都不大于`t`，这个请求是迄今为止看到的最大的一个。 它不能替代选定的请求，以更小的总处理时间获得相同数量的请求。 
6.处理完每个请求后，打印`answer`对于当前的测试用例。 

### 为什么它有效

 保持不变式，在处理排序数组的任何前缀后，`answer`是来自该前缀的最大可能的可满足请求数，并且在该大小的所有可行选择中，`total`尽可能小。 

当当前请求`t`满足`total <= t`，添加它给出`total + t <= 2t`，因此我们有一个包含另一个请求的可行选择。 由于前面的前缀最多可以包含`answer`请求，这个新选择具有最大可能的基数，并且选择尽可能小的先前总数使新的总数保持最小。 

什么时候`total > t`，添加当前请求已经需要超过`2t`时间。 具有多个请求的任何选择都必须替换一些先前选择的请求或包括当前请求。 由于当前请求至少与每个早期请求一样大，因此用它替换早期选择的请求不会产生更小的总数。 不变量说`total`已经是当前所选请求数量的最小总数，因此不存在包含一个附加请求的可行选择。 跳绳`t`因此是最优的。 

对于调度顺序来说，排序也足够了。 由于截止日期与处理时间成正比，因此处理时间越短，截止日期就越短。 以增加的方式安排选定的请求`t`是最早的截止日期顺序，满足每个前缀截止日期足以使整个选定的集合可行。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    m = int(input())
    out = []

    for case in range(1, m + 1):
        n = int(input())
        a = list(map(int, input().split()))

        a.sort()

        total = 0
        answer = 0

        for t in a:
            if total <= t:
                total += t
                answer += 1

        out.append(f"Case #{case}: {answer}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```程序首先读取测试用例的数量并独立处理每个用例。 该数组准确包含处理时间，因此不需要单独的截止日期数组。 值的截止日期`t`总是可以导出为`2t`。 

排序后，`total`包含当前请求开始之前的完成时间。 表达式`total <= t`可能看起来与原始截止日期条件不同，但它们在代数上是相同的：`total + t <= 2t`相当于`total <= t`。 

使用简化条件可以避免不必要的乘法运算，并使贪心规则更加清晰。 

平等案件必须被接受。 如果`total == t`，请求恰好在`2t`，仍然准时。 这就是为什么条件是`<=`， 不是`<`。 

Python的整数类型可以表示累计时间而不会溢出。 即使每个单独的值最多`10^9`，总数约为`10^14`。 

输出累积在`out`并在最后写一次。 这样可以避免测试用例较多时的重复输出操作。

 ## 边缘情况

 单个请求的情况很简单，但对于检查初始化很有用。 用于输入```
1
1
1000000000
```

`total`开始于`0`， 所以`0 <= 1000000000`是真的。 请求被接受，给予`Case #1: 1`。 该算法永远不需要特殊情况`n = 1`。 

相等的值揭示了边界条件。 为了```
1
3
1 1 1
```第一个请求发生变化`total`从`0`到`1`，第二个将其更改为`1`到`2`。 对于第三个请求，`total = 2`尽管`t = 1`，因此被跳过。 答案是`2`。 第二个请求恰好在时间完成`2`，它的截止日期，所以使用`<`而不是`<=`会产生错误的结果。 

跳过请求但接受稍后的请求的情况是```
1
4
1 1 1 3
```在前两个请求之后，`total = 2`。 下一个`1`失败是因为`2 > 1`，因此被忽略。 最终的请求有`t = 3`， 和`2 <= 3`，所以被接受。 最终的答案是`3`。 这说明了为什么在请求失败后必须继续扫描。 

相等边界也可能在多次请求之后出现。 为了```
1
3
1 1 2
```前两个请求产生`total = 2`。 为了`t = 2`，条件正好是`2 <= 2`，因此请求被接受。 其完成时间为`4`，正是它的最后期限`2 * 2`。 答案是`3`。 

最后，最大尺寸的情况```
1
100000
1 1 1 ... 1
```包含 100,000 个相同的请求。 前两个可以满足，因为它们的完成时间是`1`和`2`，在截止日期或之前`2`。 每个后续请求都会在之后完成`2`，因此所有剩余的请求都会被跳过。 答案是`2`。 该算法仍然只执行一种排序和一次线性扫描，因此大输入不会改变渐近行为。
