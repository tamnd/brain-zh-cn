 ## 解决方案
 ## 问题理解

 我们有时间限制`T`一个周末和一系列有序的`N`事件持续时间。 每个事件可以接受一次或拒绝。 接受的事件的总持续时间不得超过`T`，主要目标是使总数尽可能大。 同样，我们希望最大限度地减少未使用的大厅时间。 

当几个不同的子集具有相同的最大总持续时间时，预留顺序打破了平局。 较早的事件具有优先权，因此在两个有效选择不同的第一个位置，我们更喜欢包含较早事件的选择。 

输入包含多个独立的测试用例。 每个都以`T`和`N`，随后是`N`持续时间。 一行包含`0`结束输入。 官方声明称最多可预订50个，并给出2秒的时间限制，内存为256MB。 渲染的语句没有提供单独的数字上限`T`， 虽然`T`显然要足够小以充当动态程序的容量维度。 

重要的结果是算法指数`N`不合适。 和`N = 50`, 已经有`2^50`， 关于`1.13 * 10^15`，可能的子集。 一个动态规划，其第二维为`T`是自然选择，因为目标是受可用时间限制的总和。 

有几种边缘情况可能会导致看似正确的实现失败。 

考虑`5 3 6 7 8`。 每个事件都比可用的五个单元长，因此无法选择任何内容。 正确的输出是`0`。 粗心的重建例程可能会假设至少选择了一个事件并打印无效的持续时间。 

考虑`10 4 6 4 5 5`。 两个都`6 4`和`5 5`准确填满容量。 正确的输出是`6 4 10`，因为事件持续时间`6`出现在有持续时间的事件之前`5`。 仅最大化总和并保留首先找到的子集的实现可能会返回错误的决胜选择。 

考虑`5 3 1 4 5`。 最好的子集是`1 4`，其总和恰好是`5`，所以输出是`1 4 5`。 决赛`5`是总数，而不是另一个选定的事件。 将每个打印数字视为选定持续时间的解析器或重建例程可能会误解所需的输出格式。 

## 方法

 直接的方法是枚举每个子集`N`事件，计算其持续时间，如果持续时间超过则拒绝它`T`，并保留具有最大有效和的子集。 这是正确的，因为每一种可能的选择都恰好对应一个子集，因此穷举搜索不会错过最优值。 如果在生成子集的同时逐步累加总和，则工作量为`O(2^N)`子集。 和`N = 50`，这大约是`1.13 * 10^15`子集指出，远远超出了 2 秒竞赛程序可以处理的范围。 如果每个子集也扫描所有`N`events 来计算其总和，界限变为`O(N * 2^N)`， 大致`5.6 * 10^16`最坏情况下的基本事件检查。 

蛮力之所以有效，是因为有关部分选择的唯一有意义的信息是其当前的总持续时间。 许多不同的子集可以达到相同的剩余容量，一旦我们知道该容量的最佳结果，就没有必要重复探索所有这些等效的部分状态。 

这正是0/1背包的结构。 对于每个容量`j`，我们只需要知道剩余事件可实现的最佳总持续时间。 对于活动`i`有持续时间`a[i]`，只有两种可能：跳过它，给出容量的现有值`j`，或者接受它，给予`a[i]`加上最佳的容量价值`j - a[i]`。 

打破平局的规则自然地适合这种循环。 从预订列表的末尾到开头处理事件。 当当前事件和跳过它产生相同的最佳总数时，选择当前事件。 由于当前事件早于 DP 状态已表示的每个事件，因此包含它正好给出了所需的优先级。 

我们可以将数字 DP 保持在一维，从而减少内存，同时为每个事件存储一个字节，并具有记住该事件是否被选择的容量。 DP 通过事件向后处理，并通过容量向后处理，这可以防止同一事件被多次使用。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(2^N)`增量总和，`O(N2^N)`重新扫描 |`O(N)`| 太慢了 |
 | 最佳 |`O(NT)`|`O(NT)`| 已接受 |

 ## 算法演练

 1.读取可用时间`T`, 事件数量`N`，以及持续时间数组`a`。 

每个选定的事件都会消耗其持续时间，因此唯一相关的容量值是`0`通过`T`。 
2. 创建`dp[j]`，最初为零，其中`dp[j]`代表容量可实现的最佳总持续时间`j`使用迄今为止处理的事件。 

我们从右到左处理事件。 处理事件之前`i`,`dp`仅描述之后的事件`i`，这使得可以决定是否应添加当前事件，而不会意外使用它两次。 
3.创建`take[i]`作为按容量索引的字节数组。`take[i][j] = 1`意味着，在考虑事件之后`i`，容量的最优解`j`选择事件`i`。 

我们需要这些信息，因为仅知道最佳总数不足以重建哪些事件产生了它。 
4. 流程`i`从`N - 1`下降到`0`。 在当前持续时间内`w = a[i]`, 工艺能力`j`从`T`下降到`w`。 

通过参加当前事件获得的候选人是`dp[j - w] + w`。 替代方案是当前的`dp[j]`，对应于跳过事件。 
5. 如果候选人至少与`dp[j]`， 代替`dp[j]`与候选人和标记`take[i][j] = 1`。 

使用`>=`而不是`>`是打破平局规则的关键。 当两个选择产生相同的总数时，原始数组中的当前事件早于已表示的每个事件`dp`，因此选择它具有优先权。 
6. 在重建期间向前迭代原始事件数组，从`remaining = T`。 

如果`take[i][remaining]`设置完毕，输出`a[i]`并从中减去它`remaining`。 否则，跳过该事件。 重建完全遵循 DP 建造时记录的决策。 
7.最后输出`dp[T]`作为所选的总持续时间。 

在重建过程中已经按照其原始顺序遇到了选定的持续时间，因此不需要排序或反转。 

### 为什么它有效

 不变的是在处理事件之前`i`,`dp[j]`是从事件中可获得的最大总持续时间`i + 1`通过`N - 1`最多使用`j`时间。 对于活动`i`，每个最优解要么排除它，由旧的表示`dp[j]`，或包含它，表示为`a[i] + dp[j-a[i]]`。 取较大的值可以保持不变性。 当两个值相等时，选择事件`i`是正确的，因为它是最早的未解决事件，因此包含它的每个解决方案都比排除它的其他同等解决方案具有更高的优先级。 容量下降循环保证`dp[j-a[i]]`仍然只描述后面的事件，因此没有事件被使用两次。 重建遵循记录的最佳决策，给出最大总数和所需的最早优先级子集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    out = []

    while True:
        line = input().split()
        if not line:
            break

        T = int(line[0])
        if T == 0:
            break

        N = int(line[1])
        a = list(map(int, line[2:]))

        # If input lines are ever wrapped, keep reading until all N durations exist.
        while len(a) < N:
            a.extend(map(int, input().split()))

        # dp[j] = maximum total duration achievable with capacity j
        # using the events processed so far from right to left.
        dp = [0] * (T + 1)

        # take[i][j] tells us whether event i is selected in the
        # optimal solution for capacity j after considering event i.
        take = [bytearray(T + 1) for _ in range(N)]

        for i in range(N - 1, -1, -1):
            w = a[i]

            for j in range(T, w - 1, -1):
                candidate = dp[j - w] + w

                # On equality, prefer the current event because it
                # appears earlier than all events represented by dp.
                if candidate >= dp[j]:
                    dp[j] = candidate
                    take[i][j] = 1

        remaining = T
        selected = []

        for i in range(N):
            if take[i][remaining]:
                selected.append(str(a[i]))
                remaining -= a[i]

        selected.append(str(dp[T]))
        out.append(" ".join(selected))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```输入循环一次读取一个测试用例，并在第一个值为零时立即停止。 持续时间通常都出现在同一行上，但如果测试用例物理地跨输入行包裹，则随后的小循环也使解析器安全。 

这`dp`数组只有`T + 1`州。 从右到左处理事件赋予每个状态仅使用稍后事件的含义，同时处理从右到左的容量`T`down 防止从已使用同一事件更新的状态读取当前事件。 

比较使用`candidate >= dp[j]`。 严格的`>`仍会找到正确的最大总和，但不一定满足所需的保留顺序优先级。 平等必须有利于当前事件。 

这`take`数组使用`bytearray`，它为每个状态存储一个字节，而不是完整的 Python 整数对象。 这使重建信息保持紧凑，同时仍然允许直接索引。 

重建期间，`remaining`是必须由尚未检查的事件来解释的能力。 如果事件`i`被记录为对该容量的选择，减去`a[i]`准确地移动到表示剩余后缀问题的状态。 由于重建是从左到右扫描的，因此输出已经按保留顺序排列。 

Python整数不存在C或C++的定宽溢出问题，所有DP值最多为`T`因为任何选定的总数都可能超出容量。 

## 工作示例

 ### 示例案例1

 对于`T = 5`和持续时间`[1, 2, 3, 4, 5]`，DP从右向左处理数组。 该表显示了满容量状态`5`。 较小容量的决策也被存储，因为重建可能会在选择较早的事件后减少容量。 

| 活动索引 | 持续时间 |`dp[5]`加工后|`take[i][5]`|
 | ---| ---| ---| ---|
 | 4 | 5 | 5 | 是的 |
 | 3 | 4 | 5 | 没有|
 | 2 | 3 | 5 | 没有|
 | 1 | 2 | 5 | 是的 |
 | 0 | 1 | 5 | 是的 |

 最终的重建从容量开始`5`。 事件`1`选择，将剩余容量减少到`4`。 事件`2`无法改进记录的容量解决方案`4`， 事件`3`被选择，减少容量`0`，并且跳过所有后续决策。 选定的持续时间是`1`和`4`，给出输出`1 4 5`。 

事实是该事件`5`考虑容量时临时选择的`5`并不意味着它必须出现在最终答案中。 当在平局上选择较早的事件时，重建会切换到与该选择相关的较小容量状态。 这正是为什么存储每个的决策`(event, capacity)`状态是必要的。 

### 示例案例2

 对于`T = 10`和持续时间`[9, 11, 9, 3, 5, 8, 4, 9, 3, 2]`，最大可能的总数是`10`。 

| 活动索引 | 持续时间 |`dp[10]`加工后|`take[i][10]`|
 | ---| ---| ---| ---|
 | 9 | 2 | 2 | 没有|
 | 8 | 3 | 5 | 没有|
 | 7 | 9 | 9 | 没有|
 | 6 | 4 | 9 | 没有|
 | 5 | 8 | 10 | 10 是的 |
 | 4 | 5 | 10 | 10 是的 |
 | 3 | 3 | 10 | 10 是的 |
 | 2 | 9 | 10 | 10 没有|
 | 1 | 11 | 11 10 | 10 没有|
 | 0 | 9 | 10 | 10 没有|

 最终重建已满负荷启动`10`。 事件`3`, 持续时间`3`, 被选中，留下容量`7`。 事件`4`, 持续时间`5`, 被选中，留下容量`2`。 除事件外，后续事件无法提高剩余容量`9`, 持续时间`2`，因此也被选中。 结果是`3 5 2`，总共`10`。 

此示例还演示了平局打破规则。 套装`8 2`达到`10`，但是集合`3 5 2`有一个较早选择的事件，因此它具有优先权。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(NT)`| 每个`N`事件扫描容量`T`直至其持续时间。 |
 | 空间|`O(NT)`|`dp`用途`O(T)`记忆和`take`为每个事件容量对存储一个字节。 |

 最多50个事件，事件维度很小。 该算法避免了指数`2^N`完全搜索并为每个容量执行有限数量的简单 DP 转换。 内存表示也很紧凑，因为重建信息存储为字节而不是 Python 整数。

import sys
import io

def solution():
    input = sys.stdin.readline
    out = []

    while True:
        line = input().split()
        if not line:
            break

        T = int(line[0])
        if T == 0:
            break

        N = int(line[1])
        a = list(map(int, line[2:]))

        while len(a) < N:
            a.extend(map(int, input().split()))

        dp = [0] * (T + 1)
        take = [bytearray(T + 1) for _ in range(N)]

        for i in range(N - 1, -1, -1):
            w = a[i]
            for j in range(T, w - 1, -1):
                candidate = dp[j - w] + w
                if candidate >= dp[j]:
                    dp[j] = candidate
                    take[i][j] = 1

        remaining = T
        selected = []

        for i in range(N):
            if take[i][remaining]:
                selected.append(str(a[i]))
                remaining -= a[i]

        selected.append(str(dp[T]))
        out.append(" ".join(selected))

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solution()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 边缘情况

 对于`5 3 6 7 8`，每个持续时间都大于容量。 内部 DP 循环永远不会针对任何事件运行，因为`w > T`，所以每一个`dp[j]`保持为零并且每个`take[i][j]`保持未设置状态。 因此，重建不会选择任何内容并附加`dp[5] = 0`，精确地产生`0`。 

为了`10 4 6 4 5 5`，两个最早的事件总共构成`10`，而后面的两个事件也形成`10`。 当事件`1`有持续时间`4`在反向 DP 中进行处理，其包含与现有容量的最佳值相关联`10`， 所以`take[1][10]`成为现实。 后来，活动`0`有持续时间`6`还与容量的最佳价值联系在一起`10`并且是首选，因为它出现得更早。 因此重建选择`6`, 叶片容量`4`，选择较早的`4`，并产生`6 4 10`。 

为了`5 3 1 4 5`，最大总数正好是`5`。 DP 可以使用持续时间事件达到该总数`5`，但是当较早的持续时间`1`被认为是容量状态`5`还可以达到`5`通过剩余容量`4`，所以平局选择持续时间`1`。 重建然后转向产能`4`，其中持续时间`4`被选中。 输出是`1 4 5`，证明最终数字是总数而不是另一个事件。 

对于持续时间为 50 个事件的最大尺寸情况`2`和容量`100`，每个事件都可以被选择，总共给出准确的`100`。 DP达到`100`在不超过容量的情况下，并且由于所有事件都是相同的，因此所需的优先级自然会按其原始顺序选择它们。 重建在每个事件中消耗两个单位的剩余容量，直到剩余容量变为零，产生所有 50 个持续时间，然后`100`。
