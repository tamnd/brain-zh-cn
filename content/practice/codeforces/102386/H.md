 ## 解决方案
 ## 问题理解

 有两个交通灯倒计时，最初显示 (A) 和 (B)。 每过一秒，两个值都会减少一。 我们只对两个计数器仍为正值的时刻感兴趣，因为一旦计数器达到零，红灯期就会结束。 

此时，如果两个电流值之一是另一个的整数倍，则认为两个电流值是良好的。 我们需要在任一计数器归零之前计算所有美好时刻。 

假设 (A \le B)。 (t) 秒后，计数器为

 [
 A-t，\qquad B-t。 
]

 该过程对于 (t=0,1,\ldots,A-1) 有效，因此可以有多达 (10^9) 个时刻。 因此，直接模拟最多需要 (10^9) 次迭代，这远远超出了竞争性编程解决方案所能承受的范围。 这些值本身也很适合 32 位有符号整数，但中间产品是不必要的，而且 Python 的任意精度整数无论如何都消除了任何溢出问题。 

主要的边缘情况是由相等性以及计数器变为零的时刻不得被计数这一事实引起的。 例如，使用输入`1 1`，唯一的红灯时刻是初始状态`(1, 1)`，所以答案是`1`。 在第一秒之后开始的循环将错误地返回零。 有输入`2 3`，各州是`(2,3)`进而`(1,2)`。 仅有的`(1,2)`符合条件，所以答案是`1`。 粗心的实现也会检查状态`(0,1)`红色期结束后会错误地计算状态。 

平等是另一个特殊情况。 为了`5 5`，两个计数器在每个有效时刻都相等：`(5,5)`,`(4,4)`,`(3,3)`,`(2,2)`,`(1,1)`。 每个人都有资格，所以答案是`5`。 像普通除数计数问题一样处理差值 (B-A=0) 会失败，因为每个正整数都除以零，而答案则受到较短倒计时的限制。 

## 方法

 一个简单的解决方案模拟每一秒。 在时间 (t)，它计算剩余的两个值并检查其中一个是否能整除另一个。 这是正确的，因为每个可能的红灯时刻都被访问一次，并且整除性测试正是问题的条件。 

问题在于时刻的数量。 如果一个倒计时从 (1) 开始，另一个倒计时从 (10^9) 开始，则只需要检查一个时刻，但如果两者都从 (10^9) 附近开始，则可能需要检查几乎 (10^9) 个状态。 在最坏的情况下，比如`1000000000 1000000000`，模拟执行 (10^9) 次迭代，这太慢了。 

关键的观察结果是，从两个计数器中减去相同的数量可以保留它们的差异。 假设 (A \le B)，并定义

 [
 d=B-A。 
]

 (t) 秒后计数器为

 [
 x=A-t,\qquad x+d=B-t。 
]

 较小的计数器为 (x)，较大的计数器为 (x+d)。 如果(d>0)，则较大的值永远不能整除较小的正值。 因此唯一可能的条件是

 [
 x \mid (x+d)。 
]

 由于 (x\mid x)，这相当于

 [
 x\中 d.
 ]

 这彻底改变了问题。 我们不需要每秒检查一次，而只需要计算 (d) 的正除数，它们最多是较小的初始倒计时。 

差值 (d) 最多为 (10^9-1)，因此可以通过检查最多 (\sqrt d) 的可能除数对来计算其所有除数。 这样的候选者最多大约有（31623）个，与（10^9）相比是很小的。 

当（A=B）时，差异为零，先前的约简变得简并。 在这种情况下，计数器在每个有效时刻都相等，因此每个时刻都符合条件，答案很简单（A）。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(\min(A,B))) | (O(1)) | (O(1)) | 太慢了 |
 | 最佳 | (O(\sqrt{ | A-B | })) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 设 (m=\min(A,B)) 和 (M=\max(A,B))。 较小的计数器确定一盏灯变绿之前剩余多少个正状态。 
2. 如果(A=B)，则返回(A)。 两个计数器在整个红灯期间保持相等，因此 (A) 状态中的每一种状态都是有效的。 
3. 否则计算正差(d=M-m)。 在任意有效时刻，将较小的当前计数器写为(x)。 另一个计数器是(x+d)。 
4. 有效状态需要一个计数器除另一个计数器。 由于(x<x+d)，只有(x\mid x+d)可以成立。 从较大的数字中减去 (x) 得出等效条件 (x\mid d)。 
5. 较小的当前计数器取从 (m) 到 (1) 的每个整数值。 因此，答案正是 (d) 不超过 (m) 的正因数的数量。 
6. 枚举从 (1) 到 (\lfloor\sqrt d\rfloor) 的整数 (i)。 每当 (i) 除 (d) 时，(i) 和 (d/i) 都是约数。 如果最多为(m)，则分别计数，注意在(i^2=d)时不要将同一个除数计数两次。 
7. 打印累计计数。 

### 为什么它有效

 在 (A\ne B) 的每个有效时刻，令 (x) 为较小的剩余计数器。 另一个计数器正好是 (x+d)，其中 (d=|A-B|) 永远不会改变。 因为(x<x+d)，整除条件只能是(x\mid x+d)，相当于(x\mid d)。 在红灯期间，(x) 取从 (\min(A,B)) 到 (1) 的每个正整数，恰好一次。 因此，(d) 的有效矩和除数之间存在一一对应关系，最多为 (\min(A,B))。 除数枚举精确计算这些值，因此结果是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    A, B = map(int, input().split())

    m = min(A, B)
    d = abs(A - B)

    if d == 0:
        print(m)
        return

    ans = 0
    i = 1

    while i * i <= d:
        if d % i == 0:
            if i <= m:
                ans += 1

            other = d // i
            if other != i and other <= m:
                ans += 1

        i += 1

    print(ans)

if __name__ == "__main__":
    solve()
```前三个变量将输入减少为较小的倒计时 (m) 和固定差值 (d)。 使用`abs(A - B)`使代码独立于哪个原始计数器更大。 

相等情况在除数枚举之前处理。 什么时候`d == 0`，每个正状态都有相同的计数器，所以返回`m`直接避免将零视为具有普通的有限除数集。 

对于不相等的情况，循环只进行 while`i * i <= d`。 平方根下方的每个除数在其上方都有一个补除数，因此检查一侧会发现两者。 条件`other != i`防止平方除数被计算两次。 

与的比较`m`是必要的，因为并非差异的每个除数都对应于实际发生的状态。 较小的当前计数器永远不会超过其初始值，因此最多只有除数`m`可以代表有效的时刻。 

不存在涉及零的偏一问题，因为当前较小的计数器范围为`m`下降到`1`。 值为零的状态永远不会由除数枚举表示。

 对于示例 1，输入为`3 30`。 这里（m=3）和（d=27）。 可能的较小计数器值为 (3,2,1)。 只有那些除法 (27) 对应于有效时刻。

对于示例 2，输入为`16 4`。 这里（m=4）和（d=12）。 较小的计数器取值 (4,3,2,1)，并且所有四个除法 (12)。

 ## 边缘情况

 对于`1 1`，算法计算 (m=1) 和 (d=0)。 它立即返回（m=1），匹配单个有效状态`(1,1)`。 这处理了最小输入大小和零差异的特殊含义。 

为了`2 3`，我们有 (m=2) 和 (d=1)。 (1) 的唯一正因数是`1`，并且最多是`2`，所以答案是`1`。 实际状态是`(2,3)`和`(1,2)`，并且只有第二个状态有一个计数器除以另一个状态。 以下状态将是`(0,1)`，但处于红灯期之外，从不考虑。 

为了`5 5`，差值为零，因此算法返回`5`立即地。 五个州`(5,5)`,`(4,4)`,`(3,3)`,`(2,2)`， 和`(1,1)`都是有效的。 这就是为什么相等的情况不能通过普通的除数计数公式。 

为了`5 14`，差为 (9)，其约数为 (1,3,9)。 较小的计数器只能是(5,4,3,2,1)，所以只有`1`和`3`对应实际时刻。 答案是`2`。 这种情况还检查除数对逻辑，因为 (9) 是完全平方并且除数`3`必须恰好计数一次。 

为了`1000000000 1000000000`，差异为零，答案正是`1000000000`。 该算法立即生成此结果，而不是尝试十亿步模拟，这说明了为什么需要直接处理相同的情况。
