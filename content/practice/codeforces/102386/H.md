 ## 解决方案
 ## 问题理解

 在十字路口有两个倒计时，最初显示`A`和`B`。 每一秒之后，两个值同时减一。 我们只对两个倒计时仍然为正值的时刻感兴趣。 此时，如果一个是另一个的整数倍，则显示的两个数字被认为是特殊的。 

在倒计时达到零之前，我们需要对每一个这样的时刻进行计数。 由于两个计数器减少的量完全相同，因此`t`秒他们的价值是`A - t`和`B - t`。 条件是这些正值之一除以另一个。 

边界允许两者`A`和`B`一样大`10^9`。 因此，直接模拟几乎需要`10^9`迭代，这远远超出了竞争性编程解决方案所能承受的范围。 我们需要用仅检查大约的算术来代替模拟`sqrt(10^9)`，这大约是`31623`，可能性。 

有几种边界情况很容易导致差一错误。 例如，使用输入`1 1`，计数器达到零之前的唯一状态是`(1, 1)`，所以答案是`1`。 模拟直到一个值变为零并仅在递减后进行检查的循环将错误地返回`0`。 

有输入`3 30`，正状态是`(3,30)`,`(2,29)`， 和`(1,28)`。 第一个状态有`30`可除以`3`，最后一个有`28`可除以`1`，所以答案是`2`。 国家`(0,27)`不得考虑，因为一旦计数器达到零，问题就会停止。 

另一个特殊情况是相等计数器。 用于输入`5 5`，每个正状态是`(5,5)`,`(4,4)`,`(3,3)`,`(2,2)`,`(1,1)`，并且每个人都满足条件。 答案是`5`。 将计数器之间的差异视为除数目标而不单独处理零差异在这里会失败。 

## 方法

 最直接的解决办法就是模拟每一秒。 时`t`，我们计算`A - t`和`B - t`，检查是否能整除另一个，并在整除时增加答案。 这是正确的，因为灯变绿之前的每种可能状态恰好在一个整数时间发生。 

问题在于州的数量。 如果较小的初始计数器接近`10^9`，模拟执行得差不多`10^9`迭代。 即使每次迭代都有恒定的工作量，这也太慢了。 

有用的观察是计数器之间的差异永远不会改变。 不失一般性地假设`A <= B`。 后`t`秒计数器是`A - t`和`B - t`。 

他们的区别始终是`(B - t) - (A - t) = B - A`。 

称此为固定差值`d`。 因此，在每个相关时刻，较大的值是较小的值加上`d`。 

现在让较小的电流值为`x`。 较大值是较小值的整数倍的条件变为`x + d`可以整除`x`。 

自从`x`已经分裂了，这相当于`x`划分`d`。 

随着倒计时的进行，`x`取每个整数值`A`下降到`1`。 因此，原始模拟已转化为一个小得多的数论问题：计算`d`最多是`A`。 

什么时候`A = B`，差异为零。 每一个积极的`x`整除零，所以每一个`A`状态有效。 那个案子就直接处理了。 

对于非零差值，除数可以成对枚举。 如果`i`划分`d`， 然后`d / i`也是一个除数。 我们只需要尝试`i`最多`sqrt(d)`，给出时间复杂度`O(sqrt(|A-B|))`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O（分钟（A，B））| O(1) | O(1) | 太慢了 |
 | 最佳 | O(sqrt( | A-B | )) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取两个初始倒计时值并令`m = min(A, B)`。 较小的计数器是第一个达到零的计数器，因此它的正值恰好是`m, m-1, ..., 1`。 
2.如果`A == B`， 返回`A`。 两个计数器在零之前的每一时刻都相等，因此每个计数器`A`正状态满足所需条件。 
3. 否则计算`d = abs(A - B)`。 两个计数器之间的差异保持等于`d`整个倒计时。 
4. 枚举整数`i`从`1`通过`floor(sqrt(d))`。 每当`i`划分`d`， 两个都`i`和`d // i`是除数`d`。 
5. 仅当除数最多时才计算除数`m`。 这样的除数恰好对应于一个倒计时状态，其较小的显示值等于该除数。 除数大于`m`在第一个计数器达到零之前不会发生。 
6. 如果`i`和`d // i`不同的，分别计算。 什么时候`i * i == d`，这两个值是相同的除数，并且只能计算一次。 
7. 输出结果计数。 

### 为什么它有效

 假设`A <= B`，另一种情况是对称的。 在任意有效时刻，取较小的显示值`x`。 另一个值是`x + d`， 在哪里`d = B - A`是恒定的。 所需条件是一个值除另一个值。 自从`x + d`至少是`x`，这正是意味着`x`划分`x + d`。 减法`x`给出等效条件`x | d`。 

在任一值达到零之前的倒计时期间，`x`取每个整数`A`下降到`1`正好一次。 因此，有效矩和除数之间存在一一对应的关系`d`最多是`A`，即`m`在对称公式中。 该算法准确地枚举了这些除数，因此其计数正是所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    A, B = map(int, input().split())

    m = min(A, B)
    d = abs(A - B)

    if d == 0:
        print(m)
        return

    ans = 0
    i = 1

    while i * i <= d:
        if d % i == 0:
            if i <= m:
                ans += 1

            other = d // i
            if other != i and other <= m:
                ans += 1

        i += 1

    print(ans)

solve()
```前三个作业确定较小的倒计时和不变的差异。 使用`m = min(A, B)`意味着算法的其余部分不需要区分哪个原始计数器更小。 

这`d == 0`分支是必要的，因为除数枚举基于非零差的正整数除数。 当计数器相等时，每个正状态都是有效的，因此答案只是正状态的数量，`m`。 

对于非零差异，循环仅检查`i * i <= d`。 平方根下方的每个除数在其上方都有一个补除数，因此检查每对的两个成员涵盖所有除数，而无需扫描所有值`d`。 

条件`other != i`防止完全平方数被计算两次。 例如，如果`d = 36`，生成的对`i = 6`是`(6, 6)`，仅代表一个除数。 

与的比较`m`是强制执行时间界限的因素。 大于初始较小倒计时的除数永远不会显示为较小的正倒计时值，因此它不能对答案有贡献。 

Python 整数不会溢出，并且`i * i`即使在最大可能的情况下也是安全的`d`，即下面的`10^9`。 也不需要任何数组或其他辅助结构。

 ## 边缘情况

 对于`1 1`，算法集`m = 1`和`d = 0`。 它立即返回`m`，生产`1`。 这避免了尝试枚举零除数并正确计算唯一的正状态，`(1,1)`。 

为了`3 30`，算法得到`m = 3`和`d = 27`。 遇到的除数是`1`,`27`,`3`， 和`9`。 仅有的`1`和`3`至多是`m`，所以答案是`2`。 这些对应于积极的状态`(1,28)`和`(3,30)`。 国家`(0,27)`永远不会进入计数逻辑。 

为了`5 5`，差异为零。 每个正较小值`5`下降到`1`满足`x | x`，所以返回`m = 5`计算所有五个有效时刻。 没有单独的零情况的通用差除数公式无法正确表示这种情况。 

为了`1 1000000000`，差异是`999999999`较小的计数器只能显示`1`在达到零之前。 虽然差有很多约数，但只有约数`1`是可达的。 该算法过滤掉每个较大的除数`<= m`条件和回报`1`。 

为了`2 4`，差异是`2`，可达到的较小值是`2`和`1`。 两者均分`2`，所以答案是`2`。 这证实了该值`1`包括在第一个计数器达到零之前立即发生的 ，而排除随后的零值。 

为了`1000000000 1000000000`，该算法不会尝试十亿步模拟。 它立即识别相等计数器并返回`1000000000`。 这既是正确的答案，也是等计数器分支对于性能和正确性至关重要的原因。
