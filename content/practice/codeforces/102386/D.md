 ## 解决方案
 ## 问题理解

 正好有三辆坦克，编号为 1、2、3，Artem 从坦克开始`k`。 每个命令命名两个不同的坦克。 这两台坦克的乘员会交换他们的坦克，因此 Artem 仅当他当前的坦克是命令中提到的两辆坦克之一时才会移动。 

输入包含`n`命令按照给定的顺序执行。 第一行给出了命令的数量和 Artem 的初始坦克。 接下来的每一行包含一次交换中涉及的两个坦克编号。 所需的输出是处理每个命令后包含 Artem 的罐号。 

约束条件`n <= 10^5`意味着解决方案应该处理每个命令恒定的次数。 一个`O(n)`算法只执行几十万个基本操作，很容易适合正常的竞技编程时间限制。 一个`O(n^2)`模拟可能需要大约`10^10`最大输入大小的操作，这远远超出了实际情况。 

第一个边缘情况是不涉及 Artem 当前坦克的命令。 例如，```
1 1
2 3
```产生`1`。 Artem 仍留在坦克 1 中，因为交换完全发生在坦克 2 和 3 之间。如果不小心执行，在每次命令后更改 Artem 的位置，而不检查他的坦克是否参与其中，可能会错误地移动他。 

第二种边缘情况是当 Artem 在一辆交换的坦克中时，命令将他移动到另一辆坦克中。 例如，```
1 2
1 2
```产生`1`。 Artem 从坦克 2 开始，因此交换坦克 1 和 2 会将他移动到坦克 1。命令中的两个数字必须被视为交换的两个端点，而不是一个替换另一个的有序操作。 

第三个有用的情况是重复交换。 例如，```
2 3
2 3
2 3
```产生`3`。 第一次交换将 Artem 从 3 移至 2，第二次将他移回 3。如果实现意外地忽略了重复的命令或尝试简化命令而不保留其顺序，则可能会出现此错误。 

## 方法

 一种直接但不必要的昂贵方法是在每次命令后从头开始重新计算 Artem 的位置。 处理命令后`i`，它将模拟所有`i`命令来确定 Artem 在哪里，即使命令后的答案`i-1`是已知的。 模拟命令的总数为`1 + 2 + 3 + ... + n = n(n + 1) / 2`。 

为了`n = 100000`， 那是`5,000,050,000`命令模拟。 模拟本身是正确的，因为它遵循与原始过程完全相同的交换，但它多次重复几乎所有工作。 

关键的观察是我们不需要人员的全面安排。 我们只关心Artem当前的坦克。 对于一个命令`(a, b)`，只有三种可能。 如果 Artem 不在其中`a`也不`b`，他的立场保持不变。 如果他在`a`，他移动到`b`。 如果他在`b`，他移动到`a`。 

暴力重新计算之所以有效，是因为每个命令都是确定性的，但当它重复重建已计算的信息时，就会失败。 观察到下一个位置仅取决于 Artem 的当前位置和当前命令，这让我们可以将整个过程减少到每个命令一次恒定时间更新。 

由此产生的算法不需要坦克内容的数组，也不需要船员的代表。 包含 Artem 当前坦克的单个整数就足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`n`和 Artem 的初始坦克`k`。 店铺`k`作为当前位置，因为在执行任何命令之前，它正是 Artem 所在的位置。 
2. 处理`n`命令按其输入顺序排列。 对于每个命令，读取两个交换的坦克`a`和`b`。 
3. 如果当前位置等于`a`，将其更改为`b`。 阿乔姆坐在正在交换的两个坦克之一中，因此他进入了另一个坦克。 
4. 否则，如果当前位置等于`b`，将其更改为`a`。 相同的交换规则适用于相反的方向。 
5. 如果当前位置不是`a`也不`b`，保持不变。 该命令影响另外两辆坦克并且无法移动 Artem。 
6. 处理完所有命令后，打印当前位置。 每次更新都按原始顺序应用，因此该值是 Artem 的最终坦克。 

### 为什么它有效

 不变量是在处理每个命令之前，`k`存储 Artem 的当前实际坦克。 对于一个命令`(a, b)`， 如果`k`是`a`, 坦克里的船员`a`移动到坦克`b`，因此 Artem 移动到`b`。 对称情况成立时`k`是`b`，以及当`k`既不是坦克，阿尔乔姆也不动。 因此，在每个命令之后，不变量仍然为真。 最后一条命令之后，`k`因此必须是所需的最终储罐。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    for _ in range(n):
        a, b = map(int, input().split())

        if k == a:
            k = b
        elif k == b:
            k = a

    print(k)

if __name__ == "__main__":
    solve()
```第一行读取命令数和 Artem 的初始坦克。 变量`k`故意重用来表示当前坦克，因此不需要单独的状态结构。 

在循环内，每个命令仅被处理一次。 这`if`分支处理 Artem 位于命令的第一个坦克中的情况，而`elif`处理第二个水箱。 如果两个条件都不成立，则不会分配任何内容`k`，所以 Artem 留在原地。 

这些更新的顺序很重要，因为后面的命令必须在所有前面的命令之后使用 Artem 的位置。 这里没有索引转换，因为罐子已经从 1 到 3 编号。Python 整数也不关心这些值的溢出问题，尽管事实上`k`永远不会成为 1 到 3 范围之外的任何内容。 

输入仅包含一个测试用例，因此不存在外部测试用例循环。 使用`sys.stdin.readline`提供高效的输入处理`10^5`命令。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个`n`命令被读取并处理一次，不断工作。 |
 | 空间| O(1) | O(1) | 仅有的`n`,`k`,`a`， 和`b`无论命令的数量如何，都会被存储。 |

 和`n <= 10^5`，该算法仅对每个命令执行恒定量的工作，因此操作总数随输入大小线性增长。 它还不存储命令列表，使其内存使用独立于`n`。

def solve():
    input = sys.stdin.readline
    n, k = map(int, input().split())

    for _ in range(n):
        a, b = map(int, input().split())

        if k == a:
            k = b

            k = a

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample

""") == "3\n", "sample 1"

# Minimum-size input

""") == "1\n", "Artem is not involved in the only swap"

""") == "1\n", "boundary tank 3 moves to tank 1"

# Repeated swaps return Artem to the original tank

 ## 边缘情况

 当Artem不参与互换时，他的位置必须保持不变。 对于输入```
1 1
2 3
```初始位置是`1`。 该指挥部仅交换坦克`2`和`3`，所以两者都不是`k == a`也不`k == b`是真的。 该算法离开`k`等于`1`和打印`1`。 这可以防止假设每个命令都会移动 Artem 的常见错误。 

当 Artem 在坦克 2 中启动并且坦克 1 和 2 交换时，更新必须使用命令的另一个端点。 为了```
1 2
1 2
```该算法开始于`k = 2`。 第一个条件失败是因为`2 != 1`，而第二个成功是因为`2 == 2`， 所以`k`变成`1`。 输出是`1`。 

重复的交换必须单独处理。 为了```
2 3
2 3
2 3
```第一个命令发生变化`k`从`3`到`2`。 第二个命令查看更新后的值`2`并将其改回`3`。 最终输出是`3`。 这说明了为什么命令不能重新排序或被视为单个永久映射。 

最大尺寸情况不需要任何特殊逻辑。 和`100000`命令如```
100000 1
1 2
1 2
1 2
...
```该算法对每个命令执行一次恒定时间比较。 由于交换次数为偶数，Artem 从坦克 1 开始并返回坦克 1，因此输出为`1`。 状态本身永远不会随着输入而增长，这就是解决方案仍然存在的原因`O(1)`辅助空间内。
