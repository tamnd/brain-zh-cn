 ## 解决方案
 ## 问题理解

 我们有一个（n \times m）网格。 每个单元格都包含一个整数大小 (a_{ij}) 的对象。 我们需要恰好访问每个单元格一次，仅在侧相邻单元格之间移动，并且沿路线的对象大小序列必须是非递减的。 

关键限制是每个尺寸最多出现 3 次。 由于不同尺寸具有固定的相对顺序，因此具有相同尺寸的所有单元格必须连续出现在路线中。 如果尺寸 (x) 出现三次，则路线必须进入三个相应的单元格，访问所有三个单元格，然后离开组前往下一个更大的尺寸。 唯一的自由是访问最多三个单元的顺序。 

网格最多包含 (100 \cdot 100 = 10,000) 个单元格。 这使得任何以细胞数量呈指数增长的东西都完全无法使用。 有用的复杂性目标本质上是线性的或者是一个小的常数因子乘以单元格的数量。 官方声明给出了 1 秒的时间限制和 256 MB 的内存限制，这强调了解决方案应该非常积极地利用频率限制。 

在很多情况下，看似自然的构建都会失败。 

考虑单个细胞。```
1 1
7
```正确的输出很简单：```
1 1
```不同大小之间没有过渡，因此假设必须存在前一组和下一组的实现可能会错误地拒绝这种情况。 

现在考虑：```
1 3
1 2 1
```答案是：```
-1
```包含尺寸 (1) 的两个单元格在路径中必须是连续的，因为将尺寸 (2) 放置在它们之间会违反所需的顺序。 它们不相邻，因此不存在有效的路线。 如果不小心实现，只检查是否可以到达每个单独的单元格，则可能会错过这一点。 

另一个微妙的情况是：```
2 2
1 2
1 3
```有效路线是```
2 1
1 1
1 2
2 2
```两个尺寸为 (1) 的单元有两种可能的顺序。 只有从 ((2,1)) 开始的顺序才能连接到大小为 (2) 的单元格。 为相等值选择任意顺序可以拒绝可解实例。 

最后，```
1 3
1 3 2
```是不可能的。 每个尺寸都出现一次，因此根本没有内部订购选择。 所需的顺序强制为包含 (1) 的单元格，然后是包含 (2) 的单元格，然后是包含 (3) 的单元格，但前两个单元格不相邻。 仅检查单个等值组是不够的，连续组之间的转换也很重要。 

## 方法

 直接的暴力方法是按单元格的值对单元格进行排序，将它们分成相等值的组，并尝试每个组内的所有可能的排序。 这是正确的，因为一个值的单元格必须形成最终路线的一个连续段，因此为每个组选择排序完全决定了候选路线。 

问题在于组合的数量。 如果一个组有三个单元格，则最多有 (3!= 6) 个可能的订单。 在最坏的情况下，几乎所有单元都可以分为三组，为 (10,000) 个单元提供大约 (3333) 个组。 然后，强力搜索可以按以下顺序进行检查：

 [
 6^{3333}
 ]

 不同的组合。 即使仅在 (O(N)) 时间内检查每个候选者也会给出 (O(N \cdot 6^{N/3}))，这在天文数字上太大了。 

蛮力之所以有效，是因为唯一的决定是等值组内的微小排列，但它通过重新计算相同的可能前缀而浪费了大量的工作。 解锁解决方案的观察结果是，一个完整的群体只有通过其最后一个单元格才对未来产生影响。 一旦我们知道当前组是如何排序的，除了该状态是否可达之外，它之前的所有内容都无关紧要。 

这正是动态规划有用的情况。 对于每个大小组，我们枚举其单元格的所有有效排列。 仅当每对连续的单元都侧面相邻时，排列在内部才有效。 然后我们为每个排列保留一个 DP 状态，这意味着存在一条通过所有先前组的有效路径，该路径终止于该排列的第一个单元。 

当从一组移动到下一组时，我们只需要测试前一个排列的最后一个单元是否与当前排列的第一个单元相邻。 由于每组最多有 6 个排列，因此每个转换最多检查 (6 \cdot 6 = 36) 对。 

差异是巨大的：对所有组合的指数搜索变成了每组重复一次的恒定大小的 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(N \cdot 6^{N/3})) | (O(N)) | 太慢了|
 | 最佳 | (O(N \log N + N)) | (O(N)) | 已接受 |

 (N \log N) 项来自按大小对单元格进行排序。 DP 本身是 (O(N))，因为每个组最多有 6 个状态，并且每个状态最多检查 6 个先前状态。 

## 算法演练

 1. 将网格展平为 ((a_{ij}, (i,j))) 形式的对，并按对象大小对它们进行排序。 大小相等的单元格自然会变得连续。 
2. 将排序后的单元格分成大小相等的组。 由于输入限制，一个组最多包含三个单元格。 

一组中的所有单元格必须连续访问。 如果两个相同大小的单元格之间有一个较大尺寸的单元格，则该较大的对象将在相同大小的对象之前被收集，这是禁止的。 
3. 对于每个组，枚举其单元格的每个排列。 最多有 (3!= 6) 种排列。 
4. 如果排列中的两个连续单元不相邻，则丢弃该排列。 

此检查是必要的，因为必须遍历整个组，而不能将其留在大小相等的对象之间。 例如，对于三个单元，只有当第一个单元与其第二个单元相邻且第二个单元与第三个单元相邻时，该布置才可用。 
5. 对于第一组，将每个有效排列标记为可达。

该路线可以从任何地方开始，因此对第一组的第一个小区没有限制。 
6. 将剩余组从较小的值处理为较大的值。 对于当前组的每个有效排列，尝试前一个组的每个可达排列。 

令前一个排列在单元格 (x) 处结束，并让当前排列在单元格 (y) 处开始。 当 (x) 和 (y) 侧边相邻时，两个组段可以精确地连接。 
7. 当转换起作用时，标记当前排列可达并存储哪个先前排列产生它。 

存储这个前身可以让我们在 DP 完成后重建实际路线。 我们不需要在每个状态中存储整个路由，因为前驱之前的所有状态都已经由它自己的前驱链表示。 
8. 处理完最后一组后，找到该组中的任何可达排列。 如果不存在，则打印 (-1)。 
9. 否则，按照存储的前导索引向后遍历各组。 这以相反的顺序给出了每个组的选定排列。 反转选定状态的列表，并按正向顺序输出这些排列中的单元格。 

### 为什么它有效

 不变的是，可达的 DP 状态恰好表示当前等值组的一种可能的排序以及通过以该排序结束的每个较小值组的有效路由。 

对于第一组，每个内部有效排列都是可达的，因为起始单元不受限制。 对于后面的每个组，当其内部边缘有效并且其第一个单元与某个可达的先前排列的最后一个单元相邻时，该排列就被标记为可达。 因此，两个路线段合法连接，并且所有值都保持非递减状态，因为组是按大小递增顺序处理的。 

相反，假设存在一条有效的完整路径。 每个值的单元格形成一个连续的组，并且它们的顺序必须是我们枚举的排列之一。 该组内的每个连续对都是相邻的，因此排列能够通过内部检查。 两个连续值组之间的边界也是邻接边，因此相应的 DP 转换将被考虑并接受。 通过对组的归纳，DP 将保持有效路由所使用的排列可达。 因此，当不存在有效路由时，算法会准确拒绝。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from itertools import permutations

def adjacent(a, b):
    return abs(a[0] - b[0]) + abs(a[1] - b[1]) == 1

def solve():
    n, m = map(int, input().split())

    cells = []
    for i in range(n):
        row = list(map(int, input().split()))
        for j, value in enumerate(row):
            cells.append((value, (i, j)))

    cells.sort()

    groups = []
    p = 0
    total = len(cells)

    while p < total:
        q = p + 1
        while q < total and cells[q][0] == cells[p][0]:
            q += 1

        group_cells = [cells[k][1] for k in range(p, q)]

        valid_orders = []
        for order in permutations(group_cells):
            ok = True
            for k in range(len(order) - 1):
                if not adjacent(order[k], order[k + 1]):
                    ok = False
                    break
            if ok:
                valid_orders.append(order)

        if not valid_orders:
            print(-1)
            return

        groups.append(valid_orders)
        p = q

    parents = []
    reachable = [True] * len(groups[0])
    parents.append([-1] * len(groups[0]))

    for g in range(1, len(groups)):
        current = groups[g]
        previous = groups[g - 1]

        cur_reachable = [False] * len(current)
        cur_parent = [-1] * len(current)

        for ci, cur_order in enumerate(current):
            first_cell = cur_order[0]

            for pi, prev_order in enumerate(previous):
                if not reachable[pi]:
                    continue

                last_cell = prev_order[-1]

                if adjacent(last_cell, first_cell):
                    cur_reachable[ci] = True
                    cur_parent[ci] = pi
                    break

        if not any(cur_reachable):
            print(-1)
            return

        reachable = cur_reachable
        parents.append(cur_parent)

    state = -1
    for i, ok in enumerate(reachable):
        if ok:
            state = i
            break

    if state == -1:
        print(-1)
        return

    chosen = [0] * len(groups)

    for g in range(len(groups) - 1, -1, -1):
        chosen[g] = state
        if g > 0:
            state = parents[g][state]

    answer = []
    for g in range(len(groups)):
        answer.extend(groups[g][chosen[g]])

    out = []
    for i, j in answer:
        out.append(f"{i + 1} {j + 1}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```实现的第一部分将网格展平并对其进行排序。 坐标使用从零开始的索引在内部存储，这使得邻接计算和数组处理变得简单。 仅在生成答案时，它们才会转换回基于 1 的坐标。 

分组循环遍历已排序的单元格并将所有相等的值收集在一起。 由于每个值最多出现 3 次，`group_cells`从来没有超过三个元素。`itertools.permutations`因此最多生成六个候选，因此直接使用它是完全安全的。 

这`adjacent`函数使用曼哈顿距离。 当两个单元格的行差和列差之和为 1 时，这两个单元格恰好是侧面相邻的。 这里不需要显式的边界检查，因为要比较的每个坐标都已经属于网格。 

这`parents`数组为每个可达状态存储一个前驱索引。 第一组使用`-1`因为它没有前身。 对于后面的组，第一个兼容的先前状态就足够了。 无需记住所有可能的前驱，因为一个成功的前驱足以重建一条有效的路线。 

DP在处理当前组时仅保留前一组的可达性数组，但保留前一组的数组用于重建。 由于每个组最多有 6 个状态，因此即使网格有 (10,000) 个单元，该存储空间也很小。 

重建是从最终可达状态向后进行的。 每组选定的排列存储在`chosen`，并且只有在遵循了所有前驱链接之后，我们才按正向顺序遍历组。 这避免了向后打印重建路径的常见错误。 

除了坐标差和数组索引之外，任何整数算术都不会随着输入值的增长而增长，因此在 Python 中整数溢出不是问题。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(N\log N)) | 排序成本 (O(N\log N))，而每组最多有 6 个状态，每个状态最多检查 6 个先前状态 |
 | 空间| (O(N)) | 网格单元、组排列、前驱状态和重建路线每个单元仅包含恒定数量的对象 |

 这里（N=n\cdot m\le10,000）。 排序后，DP 只对每组执行少量恒定的工作，因此 (N\log N) 排序项占主导地位。 内存使用量也完全在规定的 256 MB 限制之内。

import sys
import io
import solution

def run(inp: str) -> str:
    old_input = solution.input
    old_stdout = sys.stdout

    stream = io.StringIO(inp)
    output = io.StringIO()

    solution.input = stream.readline
    sys.stdout = output

    try:
        solution.solve()
    finally:
        solution.input = old_input
        sys.stdout = old_stdout

    return output.getvalue().strip()

def validate(inp: str, out: str) -> bool:
    data = list(map(int, inp.split()))
    it = iter(data)
    n = next(it)
    m = next(it)

    a = [[next(it) for _ in range(m)] for _ in range(n)]
    total = n * m

    if out.strip() == "-1":
        return False

    vals = list(map(int, out.split()))
    if len(vals) != 2 * total:
        return False

    path = []
    for k in range(total):
        r = vals[2 * k] - 1
        c = vals[2 * k + 1] - 1

        if not (0 <= r < n and 0 <= c < m):
            return False

        path.append((r, c))

    if len(set(path)) != total:
        return False

    for k in range(1, total):
        r1, c1 = path[k - 1]
        r2, c2 = path[k]

        if abs(r1 - r2) + abs(c1 - c2) != 1:
            return False

        if a[r1][c1] > a[r2][c2]:
            return False

    return True

 |`1 3 / 5 5 5`| 任一方向上的三个相邻单元 | 一组包含最多允许的三个相等值 |
 |`2 2 / 1 2 / 1 3`| 使用两个尺寸为 (1) 的单元格的正确顺序的有效路线 | DP 必须在多个等值排列之间进行选择 |
 |`1 3 / 1 3 2`|`-1`| 连续的单例组仍然无法连接 |
 | (100\times100) 蛇标网格 | 有效的 10,000 个单元路由 | 最大维度、边界处理、排序和输出重建 |

 ## 边缘情况

 单细胞案例```
1 1
7
```恰好创建一个具有一种排列的群 ((1,1))。 第一组初始化将其标记为可达，并且重建输出该一个单元格。 不需要转换逻辑，因此算法不会意外拒绝最小的可能网格。 

对于分离的相等值，```
1 3
1 2 1
```排序后的组为 (1:{(1,1),(1,3)}) 和 (2:{(1,2)})。 大小为 (1) 的组没有有效的排列，因为它的两个单元格不相邻。 该算法在尝试任何转换之前都会拒绝。 这直接满足了相等值必须占据路由的一个连续段的要求。 

对于一组内的多个订单，```
2 2
1 2
1 3
```size-(1) 组有两种可能的排列。 ((1,1),(2,1)) 不能连接到 ((1,2))，而 ((2,1),(1,1)) 可以。 DP 最初保留这两种状态，并在处理下一组时仅消除不兼容的状态。 结果发现```
2 1
1 1
1 2
2 2
```而不是过早地做出任意的等值排序。 

对于转换失败，```
1 3
1 3 2
```每个组只有一个单元格，因此每个组都是内部有效的。 排序顺序强制为(1)、(2)、(3)的位置，即((1,1))、((1,3))、((1,2))。 第一次转换失败，因为 ((1,1)) 和 ((1,3)) 不相邻。 DP 对于第二组没有可达状态并输出`-1`。 

对于三个相等的单元格，排列枚举仍然很小。 如果单元格形成一条路径，例如```
1 3
4 4 4
```有效组包含从左到右和从右到左的顺序。 其他四个排列未通过内部邻接测试。 该算法准确地保留了实际可以遍历的两个顺序。 

最大大小的情况使用 (10,000) 个不同的值，因此每个组只有一种排列。 然后 DP 退化为一个简单的检查，检查具有下一个值的每个单元是否与前一个值相邻。 网格的蛇排序满足此条件，并且该实现可以处理所有（10,000）个单元，而不依赖于递归或指数搜索。
