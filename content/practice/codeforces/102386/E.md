 ## 解决方案
 ## 问题理解

 我们有 (n) 天的序列。 在第 (i) 天，出现主题 (a_i) 的家庭作业。 迪马要么花一天时间做一门科目目前积累的所有作业，要么什么也不做。 完成一个主题会清除迄今为止收到的该主题的所有作业。 

目标是选择尽可能少的工作日，同时确保每项任务在第 (n) 天结束时完成。 输出是一个长度为 (n) 的数组。 零表示迪马当天休息，而正值 (c) 表示他完成了科目 (c) 的所有累积作业。 

关键的观察是同一科目的作业可以一起推迟。 如果主题 (c) 的最后一份作业在 (p) 天到达，Dima 可以简单地等到 (p) 天并在那里完成 (c) 的所有作业。 由于不同的主体有不同的最后出现位置，因此这些操作永远不会冲突。 

这些限制使得这一点特别有用。 当 (n) 和 (k) 都与 (10^5) 一样大时，(O(nk)) 解决方案最多可以执行 (10^{10}) 次操作，这远远超出了典型的竞争性编程所允许的时间限制。 (O(n)) 或 (O(n+k)) 解是适当的目标。 

有几种边缘情况，粗心的实现可能会处理不当。 如果某个主题仅出现一次，则必须将其唯一出现作为其处理日。 例如，使用输入```
1 1
1
```答案一定是```
1
```因为唯一的任务必须完成。 

如果同一主题出现多次，则无需在每次作业后对其进行处理。 为了```
4 2
1 1 1 1
```答案```
0 0 0 1
```是最佳的，因为所有四项作业都可以在最后一天一起完成。 

从未出现的主体不应接受手术。 例如，```
3 5
2 2 2
```可以回答```
0 0 2
```科目 (1,3,4,5) 根本不需要任何工作。 将每个主题初始化为某个处理日而不检查它是否发生的实现将产生无效的时间表。 

最后，最后一次出现的主题是最后一天是完全有效的。 为了```
3 2
1 2 2
```我们可以输出```
0 1 2
```主题 (1) 的操作在第 2 天进行，而主题 (2) 在最终分配到达后的第 3 天进行处理。 

## 方法

 一种直接的方法是独立处理每个主题并在整个数组中搜索其最后一次出现的位置。 对于主题 (1)，从末尾扫描直到找到 (1)，然后对主题 (2) 重复相同的搜索，依此类推。 由此产生的职位正是我们应该工作的日子。 

这种方法是正确的，因为最后一次出现足以完成该主题的每项作业。 由于重复扫描同一个数组，它变得太慢。 在最坏的情况下，对于 (n=k=10^5)，这需要 (n\cdot k=10^{10}) 次数组检查。 

问题的结构让我们避免了所有的重复搜索。 当从左到右扫描一次序列时，每当我们看到主题 (a_i) 时，我们可以简单地记录它最近已知的出现时间是第 (i) 天。 扫描后，每个出现的对象的存储位置正是其最后一次出现的位置。 然后，我们将该主题放入该位置的答案中，并将每隔一天保留为零。 

不需要线段树或任何更复杂的数据结构。 “推迟”的想法是通过推迟每个受试者的工作直到其最终作业到达来实现的。 

这也给出了最小工作日数的原因是，至少出现一次的每个主题都必须至少处理一次。 否则它的任务将仍未完成。 我们的构建仅使用一个工作日来处理出现的每个主题，因此它达到了这一不可避免的下限。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(nk)) | (O(nk)) | (O(k)) | 太慢了 |
 | 最佳 | (O(n+k)) | (O(n+k)) | 已接受 |

 ## 算法演练

 1. 读取 (n)、(k) 和序列 (a)。 创建一个数组`last`按主题索引，最初用零填充。 零表示该主题尚未出现。 
2. 扫描从 (1) 到 (n) 的日期。 对于第 (i) 天，设置`last[a[i]] = i`。 如果同一主题稍后再次出现，其存储的位置将被覆盖，因此在扫描后它包含最后一次出现的位置。 
3. 创建一个由 (n) 个零组成的答案数组。 对于从 (1) 到 (k) 的每个主题 (c)，检查`last[c]`。 如果它非零，则将 (c) 放入该位置的答案中。 

这是关键的建设。 在(c)最后一次出现时，(c)的所有作业都已到达，因此在那里完成所有累积的工作即可立即完成该主题的所有作业。 
4. 打印答案数组。 每个非零位置恰好代表一个主题的最终发生，而所有其他日期都是空闲的。 

不变的是在处理完前 (i) 天后，`last[c]`恰好是主题（c）出现过的至多（i）的最大位置，如果没有出现则为零。 最后，每个出现的主题在其最终出现时仅被处理一次。 由于在任何有效的解决方案中，每个出现的主题都需要至少一个处理日，因此工作日数是最少的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    last = [0] * (k + 1)

    for i, subject in enumerate(a, start=1):
        last[subject] = i

    answer = [0] * n

    for subject in range(1, k + 1):
        pos = last[subject]
        if pos != 0:
            answer[pos - 1] = subject

    print(*answer)

if __name__ == "__main__":
    solve()
```这`last`数组对于每个可能的主题都有一个条目。 它的索引从 (1) 开始，与输入中的主题编号相匹配，而位置 0 未使用。 

枚举从 1 开始，因为问题描述的是使用基于 1 的编号的天数。 最终答案使用Python的从零开始的索引，所以`last[subject] - 1`写入时使用`answer`。 这是算法中唯一的索引转换，避免在其他地方混合这两种约定。 

当扫描输入时，分配`last[subject] = i`故意覆盖以前的位置。 我们不需要较早的事件，因为该科目积累的所有作业都可以在最后一次发生时完成。 

第二个循环检查每个可能的主题。 科目有`last[subject] == 0`从未出现过，因此不会为它们生成任何操作。 这可以防止未使用的主题意外出现在答案中。 

Python中不存在整数溢出问题，并且最大存储的天数仅为(10^5)。

 ## 边缘情况

 当一个主题只出现一次时，它的最后一次出现也是它的第一次出现。 为了```
1 1
1
```扫描集`last[1] = 1`，答案就变成了`1`。 没有办法将工作推迟到第一天之后，因此施工是强制的和最优的。 

当一个主题重复出现时，较早发生的事情就会被故意遗忘。 为了```
4 2
1 1 1 1
```为主题 (1) 存储的值依次为 (1,2,3,4)，剩下`last[1] = 4`扫描后。 因此答案只包含一个操作，`0 0 0 1`。 所有四项作业将在第 4 天之前等待处理并一起完成。 

当某些主题从未出现时，它们的`last`条目保持为零。 为了```
3 5
2 2 2
```我们结束于`last[1] = 0`,`last[2] = 3`， 和`last[3] = last[4] = last[5] = 0`。 只有位置 3 接收该值`2`，生产`0 0 2`。 该算法永远不会为缺席的主体发明工作。 

当主题的最后一次出现在最后一天时，该操作仍然合法，因为该主题的所有作业均已在该时间点到达。 为了```
3 2
1 2 2
```最终位置是`last[1] = 1`和`last[2] = 3`，所以输出是`1 0 2`。 主题 (1) 仅在其出现时完成，而主题 (2) 的两项作业均在第 3 天一起完成。 

两个重复主题之间的边界也不会引起特殊处理。 为了```
6 3
1 2 3 1 2 3
```最终位置是 (4,5,6)，给出`0 0 0 1 2 3`。 在迪玛等待期间，前三项作业仍悬而未决，然后每个科目在最终作业后仅完成一次。 

中心属性在所有这些情况下都存在：每个出现的主题在其最终出现时都被处理一次，并且每个未出现的主题都被处理零次。 由于每个出现的主题必须至少需要一个工作日，因此任何有效的时间表都不能使用比此结构更少的工作日。
