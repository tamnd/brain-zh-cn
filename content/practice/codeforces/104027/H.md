 ## 解决方案
 ## 问题理解

 我们得到两个序列，称它们为 A 和 B。每个查询给我们两个前缀：A[1..x] 和 B[1..y]。 任务是确定这两个前缀是否以对称方式“在不同元素上匹配”：出现在 A 前缀中的每个值必须已经出现在 B 前缀中，并且出现在 B 前缀中的每个值必须已经出现在 A 前缀中。 

同样，如果我们将每个前缀压缩到它包含的一组不同值中，则查询会询问这两个集合是否相同。 

微妙之处在于重复根本不重要。 只有前缀中每个值是否存在才重要，而不是它出现的次数。 

从复杂性的角度来看，此类问题的自然约束足够大，以至于不可能根据查询重新计算集合。 如果有 n 个元素和 q 个查询，则任何扫描每个查询的前缀的方法都会导致 O(nq)，这远远超出了典型的限制。 如果天真地这样做，即使独立维护每个查询的集合也会很快退化。 

第二个微妙之处是值本质上并不是很小或连续的。 任何依赖直接频率数组而不进行压缩或散列的解决方案都必须首先对值进行归一化或使用映射，如果重复执行，这可能会成为瓶颈。 

当一侧包含另一侧不包含的重复项时，或者当元素以不同的顺序出现但具有相同的集合时，就会出现典型的失败情况。 

例如，假设 A = [1, 2, 1, 3] 且 B = [1, 3, 2]。 对于 x = 4, y = 3，两个前缀都恰好包含 {1, 2, 3}，所以答案是 YES。 比较前缀和或频率而不是不同集合的粗心实现会错误地将其视为不同。 

另一种边缘情况是当一个前缀严格较小但已包含另一个前缀的所有不同元素时。 例如，A = [1, 2, 3, 3, 3]，B = [1, 2, 3, 4]。 在 x = 5、y = 3 时，A 有 {1, 2, 3}，B 有 {1, 2, 3, 4}，所以即使大多数元素重叠，答案是否定的。 

核心困难是在许多查询下有效维护前缀集。 

## 方法

 一种直接的方法是为 A 的每个前缀和 B 的每个前缀构建不同的集合。对于每个前缀，我们存储到目前为止看到的元素集合，然后对于每个查询，我们比较两个集合。 

这是正确的，但是按前缀构建集合并按查询比较它们的成本很高。 即使集合比较经过优化，每次比较也会花费前缀中不同元素数量的线性时间。 在所有元素都不同的最坏情况下，每个查询的成本为 O(n)，导致总时间为 O(nq)。 

关键的观察是，对于前缀来说，重要的不是完整的集合结构，而是两个前缀是否包含完全相同的不同元素。 这建议将每个前缀变成一个紧凑的指纹。 如果两个前缀具有相同的集合，则它们的指纹必须匹配。 如果我们可以维护一组不同元素的滚动表示，我们就可以在 O(1) 内回答每个查询。 

执行此操作的标准方法是为每个不同值分配一个随机散列，并为每个前缀维护迄今为止看到的所有不同元素的散列的 XOR。 重要的技巧是重复项不能计算两次，因此我们跟踪元素是否已经出现在前缀中。 当我们第一次看到一个元素时，我们将其哈希值异或到前缀值中； 稍后发生的事件将被忽略。 

这将每个前缀转换为单个整数（或为了安全起见的整数对），并且集合的相等性变为散列的相等性。 然后每个查询减少为比较两个预先计算的前缀哈希。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（根据查询设置）| O(nq) | O(n) | 太慢了|
 | 前缀不同的哈希 | O(n + q) | O(n) | 已接受 |

 ## 算法演练

 我们分别为 A 和 B 构建解决方案。 

1. 为每个可能的值分配一个随机的 64 位整数哈希值。 这充当该值的独特指纹贡献。 
2. 从左到右扫描数组 A，同时维护一个布尔数组或哈希图，指示某个值是否已经出现。 维持运行的 XOR 值`hashA[i]`表示 A[1..i] 中不同元素的集合。 如果 A[i] 第一次出现，则将其哈希值异或到运行值中。 
3. 对数组 B 重复相同的过程，生成`hashB[j]`。 
4. 对于每个查询 (x, y)，比较`hashA[x]`和`hashB[y]`。 如果相等则输出YES，否则输出NO。 

关键的设计选择是忽略重复发生的情况。 如果没有这个，异或将错误地消除重复项并破坏正确性。 

### 为什么它有效

 对于任何前缀，每个值仅贡献一次当且仅当它在该前缀中至少出现一次时。 XOR 累加的行为就像一个集合指示器，因为 XOR 是可交换的且自逆的。 由于我们仅在值第一次出现时插入该值，因此前缀哈希恰好是该前缀中所有不同元素的哈希值的异或。 当且仅当两个前缀对相同的哈希多重集进行异或时，它们才具有相同的不同集合，这在使用足够大的随机哈希时以高概率产生相同的结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))

    import random
    rnd = random.getrandbits

    # assign hash per value
    H = {}

    def get_hash(x):
        if x not in H:
            H[x] = rnd(64)
        return H[x]

    seenA = set()
    seenB = set()

    prefA = [0] * (n + 1)
    prefB = [0] * (m + 1)

    cur = 0
    for i in range(1, n + 1):
        v = A[i - 1]
        if v not in seenA:
            seenA.add(v)
            cur ^= get_hash(v)
        prefA[i] = cur

    cur = 0
    for i in range(1, m + 1):
        v = B[i - 1]
        if v not in seenB:
            seenB.add(v)
            cur ^= get_hash(v)
        prefB[i] = cur

    out = []
    for _ in range(q):
        x, y = map(int, input().split())
        out.append("YES" if prefA[x] == prefB[y] else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案独立地为两个数组构建前缀表示。 重要的实施细节是`seenA`和`seenB`套。 如果没有它们，重复出现将错误地切换 XOR 值，从而破坏“仅设置”行为。 

另一个微妙之处是使用基于字典的随机哈希分配，而不是依赖于 Python 的内置哈希，后者按进程加盐，并且以受控方式在运行中不稳定。 显式随机 64 位整数可确保再现性。 

最后，前缀数组是 1 索引的，以简化查询处理并避免重复的索引移位。

 ## 边缘情况

 一个重要的边缘情况是大量重复。 对于 A = [5,5,5,5] 和 B = [5]，A 的每个前缀在第一次出现后应表现相同。 该算法处理这个问题是因为`seenA`防止重复的 XOR 切换，因此前缀哈希在前 5 个之后立即稳定。 

另一种边缘情况是元素以不同方式交错但集合匹配。 对于 A = [1,2,1,3,2] 和 B = [3,2,1]，即使 B 更短且无序，最终的前缀哈希也必须匹配。 该算法正确地将两者简化为 XOR(h(1), h(2), h(3))。 

第三种边缘情况是使用相同的 (x, y) 重复查询。 由于答案仅取决于预先计算的数组，因此重复查询不会产生额外的状态更改，并且始终返回一致的结果而无需重新计算。
