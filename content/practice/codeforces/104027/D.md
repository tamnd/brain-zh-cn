 ## 解决方案
 ## 问题理解

 我们收到一系列订单，每个订单都有一个价格，以及一系列折扣优惠券。 每张优惠券都有一个阈值和一个折扣值。 仅当订单价格至少与优惠券阈值一样大时，优惠券才能应用于订单。 如果应用它，订单的成本会减少其折扣值。 

每张优惠券最多可使用一次。 对于每个订单，我们希望决定使用哪张符合条件的优惠券，以便最大限度地减少所有订单花费的总金额。 如果一个订单可以使用多张优惠券，我们总是希望选择折扣最大的一张，因为在有较大折扣的情况下使用较小的优惠券只会增加总成本，而不会影响未来的可行性。 

任务是在这些约束下将优惠券最佳地分配给订单后计算最小总成本。 

从约束的角度来看，此类 Codeforces 问题的自然规模约为$10^5$订单和$10^5$优惠券。 这立即排除了任何二次匹配策略，即我们检查每个订单的每张优惠券。 一个天真的$O(nm)$模拟最多需要$10^{10}$操作，这在两秒钟内是不可能的。 

关键的困难在于优惠券的适用性取决于当前订单的价格，并且优惠券会随着我们的使用而消耗，因此问题类似于具有资格限制的动态分配。 

一些边缘情况对于正确性很重要：

 如果所有订单都比每个优惠券阈值便宜，则没有优惠券可用，因此答案只是所有订单价格的总和。 尝试在不检查可行性的情况下贪婪地分配优惠券的幼稚方法可能会错误地“强制”使用并产生无效的负面贡献。 

如果所有优惠券都为零折扣，则任何策略都有效，但粗心的实施可能仍会尝试维护不必要的结构或错误处理空堆。 

如果多个优惠券共享相同的阈值和折扣，只要我们始终选择可用的最大折扣，打破平局并不重要。 

## 方法

 暴力破解的想法很简单：独立处理每个订单，扫描所有未使用的优惠券，过滤当前订单满足阈值的优惠券，选择折扣最大的优惠券，应用它，并将其标记为已使用。 这是正确的，因为它直接强制执行每个订单的可行性和最佳本地选择。 

然而，这种方法需要检查每个订单的所有剩余优惠券。 和$n$订单和$m$优惠券，这导致$O(nm)$运营。 在最坏的情况下，两者都$10^5$，这变成了$10^{10}$，这远远超出了任何实际限制。 

关键的观察是，可行性仅取决于订单价格是否超过优惠券阈值，并且这个条件是单调的，因为一旦订单大到足以使用优惠券，如果我们按递增顺序处理，那么未来所有更大的订单也​​将能够使用它。 这建议对订单和优惠券进行排序。 

按阈值和订单价值排序后，我们可以按升序扫描订单并维护一组当前符合条件的所有优惠券。 在所有符合条件的优惠券中，我们总是想要折扣最大的一张。 这正是一个数据结构问题：我们需要维护一个动态集，支持插入新的合格优惠券和提取最大折扣。 

最大堆干净地解决了这个问题。 我们在迭代订单时插入符合条件的优惠券，并为每个订单提取最佳的可用优惠券。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(nm)$|$O(m)$| 太慢了|
 | 最优（排序+堆） |$O((n+m)\log m)$|$O(m)$| 已接受 |

 ## 算法演练

 1. 将所有订单按价格升序排列。 这确保了优惠券一旦符合资格，仅按价值对所有后续订单保持资格，但不一定在之前有用。 
2. 按阈值升序对所有优惠券进行排序。 这使我们能够随着订单价值的增加逐步激活优惠券。 
3. 维护一个指向优惠券列表的指针和一个最大堆，用于存储已满足阈值的所有优惠券的折扣。 
4. 按排序顺序迭代订单。 对于每个订单，首先将阈值小于或等于当前订单价格的每张优惠券推入堆中。 此步骤确保堆中准确包含可以合法应用的优惠券集。 
5. 如果堆非空，则弹出最大优惠券并从当前订单价格中减去。 这是正确的，因为任何其他可用的优惠券都会产生较小或相同的折扣，并且永远不会改善未来的结果。 
6. 将（可能减少的）订单成本添加到总答案中。 
7. 继续，直到处理完所有订单。 

关键的决定始终是在可行的优惠券中选择最大折扣。 任何替代选择要么会浪费更好的优惠券，要么将其留到以后的订单中，但可能无法使用。 

### 为什么它有效

 在任何时候，堆都准确地包含可用于排序扫描中当前或未来订单的优惠券。 由于优惠券是一次性的，因此提前分配优惠券并不妨碍以后更好的分配，除非通过消费。 总是获取最大可用折扣的贪婪选择确保我们永远不会在相同或较早的约束水平下使用更差的优惠券时，不会闲置更好的优惠券。 这就建立了一个交换论点：如果最优解决方案使用较小的折扣，而同时存在较大的折扣，则交换它们不会违反可行性，并且会严格改善或保留总结果。 逐步重复这个论证可以保证全局最优性。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    orders = list(map(int, input().split()))
    coupons = []
    
    for _ in range(m):
        x, y = map(int, input().split())
        coupons.append((x, y))
    
    orders.sort()
    coupons.sort()
    
    total = 0
    heap = []
    
    i = 0
    for price in orders:
        while i < m and coupons[i][0] <= price:
            heapq.heappush(heap, -coupons[i][1])
            i += 1
        
        if heap:
            best = -heapq.heappop(heap)
            price -= best
        
        total += price
    
    print(total)

if __name__ == "__main__":
    solve()
```代码直接遵循扫描线结构。 对两个数组进行排序可确保优惠券的单调激活。 指针`i`保证每张优惠券只处理一次，总体上提供线性插入成本。 堆存储负值，因为Python默认提供了最小堆，所以求反模拟了最大堆。 

一个微妙的点是，每张优惠券一旦使用就会从堆中删除，确保自然执行“一次性”约束。 

## 工作示例

 考虑一个订单示例`[3, 8, 10]`和优惠券`[(2, 1), (5, 4), (7, 3)]`。 

### 轨迹 1

 | 订单| 激活优惠券 | 堆（折扣）| 选择| 订单成本|
 | ---| ---| ---| ---| ---|
 | 3 | (2,1) | [1] | 1 | 2 |
 | 8 | (5,4), (7,3) | [4,3]| 4 | 4 |
 | 10 | 10 没有新的| [3] | 3 | 7 |

 最终总数为$2 + 4 + 7 = 13$。 

此跟踪显示激活如何仅依赖于阈值交叉，以及堆如何始终选择最强的可用优惠券。 

### 轨迹 2

 订单`[5, 5, 5]`, 优惠券`[(5, 10), (5, 3)]`。 

| 订单| 激活优惠券 | 堆| 选择| 订单成本|
 | ---| ---| ---| ---| ---|
 | 5 | 两张优惠券| [10, 3] | 10 | 10 -5 |
 | 5 | 已所剩无几 | [3] | 3 | 2 |
 | 5 | 已所剩无几 | []| - | 5 |

 总计为$-5 + 2 + 5 = 2$。 

这证明了对重用约束的正确处理：一旦优惠券被拿走，它就会消失，剩余的订单也会相应地进行调整。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O((n + m)\log m)$| 每张优惠券被推送一次，也可能被弹出一次； 堆操作是对数的 |
 | 空间|$O(m)$| 堆存储最多所有优惠券|

 排序和堆操作对于典型的 Codeforces 限制来说足够高效$10^5$元素，在时间限制内轻松完成。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import heapq

    input = sys.stdin.readline
    n, m = map(int, input().split())
    orders = list(map(int, input().split()))
    coupons = [tuple(map(int, input().split())) for _ in range(m)]

    orders.sort()
    coupons.sort()

    total = 0
    heap = []
    i = 0

    for price in orders:
        while i < m and coupons[i][0] <= price:
            heapq.heappush(heap, -coupons[i][1])
            i += 1

        if heap:
            price -= -heapq.heappop(heap)

        total += price

    return str(total)

# provided sample-like tests

 ## 边缘情况

 一种边缘情况是存在优惠券但没有资格获得早期订单。 对于像这样的输入`orders = [1, 2, 3]`和`coupons = [(10, 5)]`，堆在整个初始迭代中保持为空。 该算法正确地将每个订单不变地相加，产生总和`6`。 

另一个边缘情况是当多个优惠券在同一订单范围内符合资格时。 假设订单是`10`和优惠券是`(5,1), (5,9), (5,4)`。 激活后，堆包含所有三个折扣，提取可确保`9`首先使用。 无论插入顺序如何，堆不变量都保证正确性。 

最后一个边缘情况是耗尽：一旦使用了所有优惠券，堆就会变空，后续订单只需贡献其原始价格。 这是自然处理的，因为当堆为空时不会尝试其他操作。
