 ## 问题理解

 我们收到了一系列糖果包。 每包包含 2 颗糖果或 3 颗糖果。 任务是确定是否可以将所有糖果分发给三个人，使每个人收到的糖果总数完全相同。 

输入有效地描述了仅由值 2 和 3 组成的多重集。输出是一个简单的可行性答案：是否存在一种方法将所有这些包分为三组，使得每组中的总和相同。 

第一个结构性约束来自总和。 如果糖果总数为`S`，那么一个必要条件是`S`能被3整除。否则，无论怎样排列都不存在等分。 

第二个约束是组合而不是算术。 即使`S / 3`是一个整数，我们必须确保 2 和 3 的多重集可以分为三个子集，每个子​​集之和为`S / 3`。 这是一个受约束的子集和划分问题，具有非常小的项目权重字母表。 

当使用 2 和 3 计数的贪婪推理而不考虑跨组交互时，会出现微妙的边缘情况。 例如，考虑包`[3, 3, 2, 2, 2]`。 总和是`12`，所以每个人都必须得到`4`。 天真的尝试可能会尝试分组`(3+1)`这是不可能的，或者独立对待 2 和 3，没有注意到有效分区需要混合两种类型。 

另一种边缘情况是总和可被 3 整除，但由于不可分性约束不存在分区。 例如，`[3, 3, 3, 2]`有总和`11`，已经无法整除，但即使是像这样的变体`[3, 3, 2, 2]`需要仔细的赋值推理。 

关键的难点不是算术目标，而是离散的积木2和3能否同时排列成三个相等的和。 

## 方法

 最直接的方法是将其视为分区问题。 由于每个人都必须准确地收到`S / 3`糖果，我们可以考虑将每个包分配到三个箱子之一，并检查任何分配是否有效。 

一个蛮力的想法是枚举将每个包分配给三个人之一的所有方法。 和`n`包，这会导致`3^n`可能性太大了。 

稍微结构化一点的蛮力观察到每个人的总和是固定的，因此我们只需要考虑子集组合。 我们可以枚举所有包的子集，其总和为`S / 3`。 假设有`L`这样的子集。 然后我们尝试所有的子集三元组，看看它们是否形成一个分区。 这导致`O(L^3)`检查。 在最坏的情况下，`L`它本身可以是指数的，因为即使很小的权重的子集总和也会产生许多组合。 

关键的观察是，我们实际上不需要在任意子集级别上推理单个分配。 由于所有权重仅为 2 或 3，因此该结构受到高度约束。 任何有效的解决方案都相当于将一些 3 件装和一些 2 件装组合在一起，偶尔混合，但混合可以标准化。 

一种更清晰的看待方式是固定一个人的份额`T = S / 3`。 我们只需要决定每个人有多少 3 件装和 2 件装。 让`x`是分配的 2 包数量，`y`是指定的 3 件装数量。 那么每个人都必须满足`2x + 3y = T`。 

所以问题就变成了：我们能否将所有 2 包和 3 包分成三组，每组都遵循相同的线性方程？ 这将全局划分问题简化为检查 2 和 3 的计数是否可以在三个相同的线性表示中一致地分解。 

我们不是搜索分配，而是枚举所有有效的`(x, y)`一个人的解决方案，然后检查三个这样的解决方案是否可以共同消耗所有项目。 这极大地减少了状态空间，因为方程`2x + 3y = T`只有`O(T)`解决方案，并且在实践中很少有`x`是有界的，奇偶性限制了可行性。 

然后，我们检查这些候选解决方案的所有三元组，看看它们是否完全覆盖了 2 和 3 的可用数量。 

这将组合划分问题转化为可行线性分解的有界枚举。

 ## 算法演练

 1. 计算总和`S`所有糖果。 如果`S % 3 != 0`，立即停止，因为等分是不可能的。 
2. 设定每人目标`T = S / 3`。 这是三组中每组必须达到的固定总和。 
3.让`c2`是 2 件装的数量，并且`c3`是 3 件装的数量。 我们现在将一个人的选择描述为选择`x`两两和`y`三这样`2x + 3y = T`。 
4. 枚举所有对`(x, y)`满足方程和可行性约束`0 <= x <= c2`和`0 <= y <= c3`。 每对代表一个人可能的形成方式。 
5. 存储所有有效的`(x, y)`列表中的对。 每个候选代表最终分区的三分之一的分解。 
6. 尝试所有候选三元组`(i, j, k)`从这个列表中。 对于每个三元组，检查是否：`x_i + x_j + x_k = c2`和`y_i + y_j + y_k = c3`。 

这可确保所有 2 件装和 3 件装在三个人中恰好使用一次。 
7. 如果任何三元组满足两个方程，则返回“YES”。 否则返回“NO”。 

### 为什么它有效

 任何有效的分区都会导致每个人收到多少 2 件装和 3 件装的选择，因此它对应于三对`(x, y)`坐
