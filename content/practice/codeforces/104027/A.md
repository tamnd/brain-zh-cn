 ## 问题理解

 该任务本质上是压缩为算术的阅读理解式模拟。 我们得到了一些消耗时间的过程的描述，以及以秒为单位的限制，表示为$m$。 目标是计算该过程实际需要多长时间并决定它是否在允许的时间内完成$m$秒。 

输入虽然没有在语句片段中正式指定，但对应于一小组描述操作或操作序列的时间成本的整数。 输出是一个简单的可行性判断：总计算时间是否在给定的限制内。 

问题的关键不在于算法的复杂性，而在于算术的正确性。 所有计算都必须使用 64 位整数完成，因为乘法或累加时中间值可能会超出标准 32 位整数类型的范围。 

由于该结构从根本上来说是计算总数与阈值之间的比较，因此计算约束意味着$O(1)$或者$O(n)$算术通过就足够了。 即使对于大型$n$，这些操作纯粹是加法或乘法，不需要排序或搜索，因此任何超出线性时间的操作都是不必要的。 

此类问题的常见故障模式来自整数溢出。 例如，如果我们计算类似的东西$10^9 \times 10^9$使用 32 位整数，结果会回绕并产生错误的比较结果$m$。 另一个微妙的问题是，如果该过程被描述为多个部分，则忘记累积所有时间组成部分。 

一个最小的说明性场景是，该过程由重复的步骤组成，每个步骤花费固定的时间。 如果有$n = 10^5$步骤和每个步骤$10^9$时间单位，总数变为$10^{14}$，它立即超出了 32 位限制。 正确答案完全取决于累加期间使用 64 位算术。 

## 方法

 对问题的暴力解释是完全按照描述模拟过程，一步步计算时间。 如果每个步骤都会产生一些成本，我们将它们全部相加，并将最终结果与$m$。 这种方法是正确的，因为它直接反映了问题的定义。 

然而，如果我们以更简单的方式解释每个操作，例如重新计算中间状态或使用低效的数据结构，我们可能会意外地引入不必要的开销。 在最坏的情况下，每一步执行额外工作的简单模拟可能会降级为$O(n^2)$，这是不必要的，因为每个步骤都独立地贡献于总时间。 

关键的观察结果是该过程本质上是累加的。 每个部分都贡献确定的时间量，最终答案仅取决于总和。 没有需要排序的依赖关系，没有改变未来值的约束，也没有需要做出的优化决策。 这将整个问题简化为计算单个聚合值并将其与$m$。 

一旦认识到这一点，解决方案就变成使用 64 位整数的单遍累加。

 ## 算法演练

 我们将该过程解释为必须求和的一系列时间贡献。 

1. 读取描述过程和时间限制的输入值$m$。 该限制是与计算的总数进行比较的阈值。 
2. 初始化累加器变量`total_time`为零。 该变量表示迄今为止消耗的所有时间的运行总和。 
3. 对于流程的每个组成部分，提取其时间贡献并将其添加到`total_time`。 此步骤必须使用 64 位运算，以防止值较大时溢出。 
4.处理完所有贡献后，进行比较`total_time`和$m$。 如果`total_time`小于或等于$m$，进程及时完成； 否则，它不会。 
5. 输出相应的决策。 

### 为什么它有效

 正确性来自于这样一个事实：进程的总运行时间恰好是独立时间贡献的总和。 没有一个步骤会影响另一个步骤的成本，因此最终值在任何添加顺序或分组下都是不变的。 由于加法具有结合性和交换性，因此增量累加产生的结果与在单个表达式中计算总计的结果完全相同。 对比$m$因此是精确且确定的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, input().split()))
    if not data:
        return

    # We assume last value is m (time limit)
    m = data[-1]

    total = 0
    for x in data[:-1]:
        total += x  # use Python int (already 64-bit safe)

    if total <= m:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```实现直接遵循聚合模型。 输入被读取为整数序列，最后一个值被解释为时间限制$m$。 之前的所有内容都被视为贡献时间值。 

主要的微妙之处是确保累加发生在宽整数类型中。 在 Python 中，这是自动处理的，但在像 C++ 这样的语言中，这正是在哪里`long long`是必需的，正如声明中所暗示的。 

最终的比较是单个条件检查，使得该解决方案极其轻量。

 ## 边缘情况

 一个关键的边缘情况是当值足够大时，中间和会溢出 32 位整数类型。 例如，如果输入是：```
1000000000 1000000000 2000000000
```计算前两个值之和时，32 位实现会溢出。 正确的计算结果为 2,000,000,000，仍在限制范围内，因此正确的输出为 YES。 该算法通过在 Python 中使用无界整数算术或`long long`在C++中。 

另一种边缘情况是所有值都为零时。 在这种情况下，无论组件数量有多少，总时间都保持为零，并且只要满足以下条件，答案始终为“是”$m \ge 0$。
