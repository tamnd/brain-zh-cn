 ## 解决方案
 ## 问题理解

 我们得到了一个用虚构的 Pindows 操作系统编写的命令行字符串。 命令行由词位组成，词位是传递给程序的标记。 

词位有两种出现方式。 

正常的词位是非空格字符的最大序列。 例如，在：```
run.exe one two
```词位是`run.exe`,`one`， 和`two`。 

引用的词位开头为`"`并以匹配结束`"`。 这些引号之间的所有内容都属于一个词位，包括空格。 内容甚至可能是空的。 例如：```
"a b" ""
```包含两个词位：`a b`和空字符串。 

保证输入是有效的命令行。 引号永远不会含糊，带引号的块正确闭合，并且每个词位与相邻词位之间通过空格或字符串末尾分隔。 

我们的任务只是解析命令行并在其自己的行上打印每个词素，周围是`<`和`>`。 

字符串长度最多为$10^5$。 这立即排除了任何重复复制大子字符串或重新扫描部分输入的方法。 线性扫描是自然的目标，因为我们只需要识别令牌边界一次。 

一些边缘情况值得关注。 

考虑一个空的引用参数：```
""
```正确的输出是：```
<>
```假设每个标记至少包含一个字符的解析器会意外地丢弃该参数。 

考虑一个包含空格的引用参数：```
"a b c"
```正确的输出是：```
<a b c>
```按空格分割输入会错误地生成三个单独的部分。 

考虑由单个空格组成的引用参数：```
" "
```正确的输出是：```
< >
```这与空参数不同，因此我们必须准确保留引号内的每个字符。 

最后，考虑相邻的标点符号：```
run.exe one, two!
```正确的输出是：```
<run.exe>
<one,>
<two!>
```标点符号是词位的一部分。 只有空格和引号具有特殊含义。 

## 方法

 最直接的想法就是逐字符处理字符串，构建当前的词位。 每当我们遇到引号外的空格时，我们就会完成当前的词位。 每当我们遇到引号时，我们都会找到匹配的结束引号，并将它们之间的所有内容视为一个标记。 

暴力实现可能会重复向前搜索匹配的引号并重复创建新的子字符串。 由于每次搜索可能会遍历字符串的很大一部分，因此最坏情况的复杂性可能会降低到$O(n^2)$。 和$n = 10^5$，这变得太昂贵了。 

输入的结构为我们提供了更好的选择。 每个角色都属于以下三个类别之一：

 1. 引号外的分隔符空格。 
2. 引用词位内的字符。 
3. 未加引号的词位的字符。 

一旦一个字符被处理过，我们就不需要再看它了。 这建议进行一次从左到右的扫描。 

关键的观察是引用的词位总是以`"`，并且该语句保证命令行有效。 一旦我们看到开盘报价，我们就可以继续前进，直到相应的收盘报价。 它们之间的内容构成一个完整的词位。 对于未引用的词位，我们前进到下一个空格。 

每个字符都会被访问恒定的次数，从而给出线性解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取整个输入行。 
2. 维护索引`i`指向当前位置。 
3.如果`s[i]`是一个空格，前进`i`。 

词位之外的空格只是分隔符，因此它们不属于任何标记。 
4. 如果`s[i]`是双引号，开始解析引用的词位。 

超过开盘报价，记住起始位置，然后继续，直到匹配的收盘报价。 这些引号之间的子串是一个词位。 
5. 存储该词位并前进到收盘价之后。 
6. 否则，开始解析未加引号的词位。 

继续向前移动，直到到达空格或字符串末尾。 遍历的字符形成一个词位。 
7. 存储词位。 
8. 重复此操作，直到处理完整个字符串。 
9. 打印每个存储的词位，周围是`<`和`>`。 

### 为什么它有效

 在每个位置，解析器要么位于词位外部，要么恰好位于一个词位内部。 输入保证引号正确匹配，并且词位由空格或字符串边界分隔。 

当遇到引号时，根据定义，匹配引号之前的每个字符都属于同一个词位。 当遇到非引号、非空格字符时，词位将延伸到下一个分隔符空格。 这些正是命令行规范所使用的规则。 

由于每个词位都是根据其定义的边界条件提取的，并且每个字符恰好属于一个处理区域，因此该算法精确地输出命令行表示的词位。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().rstrip('\n')

    n = len(s)
    i = 0
    tokens = []

    while i < n:
        if s[i] == ' ':
            i += 1
            continue

        if s[i] == '"':
            i += 1
            start = i

            while i < n and s[i] != '"':
                i += 1

            tokens.append(s[start:i])
            i += 1  # skip closing quote
        else:
            start = i

            while i < n and s[i] != ' ':
                i += 1

            tokens.append(s[start:i])

    sys.stdout.write('\n'.join(f'<{token}>' for token in tokens))

if __name__ == "__main__":
    solve()
```实现直接遵循解析逻辑。 

外循环始终指向第一个未处理的字符。 空格会被立即跳过，因为它们从不属于词位。 

当遇到报价时，代码会在开盘报价之后立即记录仓位，并前进直至收盘报价。 切片`s[start:i]`完全包含引用的内容。 这自然会处理空字符串，因为如果引号相邻，`start == i`并且切片是空的。 

对于普通词位，解析器前进直到下一个空格。 由于引号不能出现在有效输入中未加引号的词位内，因此不需要进行额外的检查。 

一个常见的错误是使用`split()`在输入上。 这会破坏有关引用部分的信息，并且不能表示空参数。 另一个微妙的点是在引用的词位内保留空格。 子字符串提取会自动执行此操作，因为仅删除外部引号字符。

 ## 边缘情况

 考虑输入：```
""
```解析器看到一个开始引号，立即前进到下一个引号，并提取它们之间的子字符串。 该子字符串的长度为零，因此存储的词素是空字符串。 输出变为：```
<>
```不需要特殊情况代码。 

考虑：```
" "
```进入引号模式后，解析器会收集引号之间的单个空格。 提取的子串是`" "`而不是`""`，生产：```
< >
```这证实了引号内的空格是数据，而不是分隔符。 

考虑：```
"a b" c
```第一个词素完全在引号内解析，产生`a b`。 在结束引号之后，解析器会跳过分隔空格并解析未引用的词位`c`。 输出是：```
<a b>
<c>
```内部空格仍然是第一个参数的一部分，因为引用模式会忽略分隔符语义，直到到达匹配的结束引号为止。 

考虑：```
run.exe one, two!
```解析器从不特殊对待标点符号。 它仅在到达空格时停止未加引号的解析。 提取的词位是：```
<run.exe>
<one,>
<two!>
```这将验证标点符号是否属于该标记，与输入中显示的完全一样。
