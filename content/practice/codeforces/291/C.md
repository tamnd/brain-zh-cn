 ## 解决方案
 ## 问题理解

 每个 IP 地址实际上都是一个以点分十进制形式书写的 32 位整数。 子网掩码也是一个 32 位值，但它必须具有非常具体的形状：一定数量的前导`1`位后面跟着一定数量的尾随`0`位。 

当 IP 地址与子网掩码进行 AND 运算时，结果就是网络地址。 如果两个 IP 在应用掩码后产生相同的结果，则它们属于同一网络。 

我们最多有 100,000 个不同的 IP 地址和一个目标号码`k`。 我们必须找到一个子网掩码，使得给定的地址完全属于`k`不同的网络。 如果有多个掩码有效，我们必须输出最少的一个`1`位。 由于子网掩码由前导掩码组成，这意味着我们希望所有有效掩码中的前缀长度尽可能短。 如果没有掩模准确产生`k`网络，我们输出`-1`。 

约束条件`n ≤ 100000`立即排除任何比较所有地址对的情况。 一个`O(n²)`解决方案大约需要`10^10`最坏情况下的操作。 我们需要一些接近的东西`O(n log n)`或者`O(32n)`。 

一些边缘情况很容易被错误处理。 

认为`k = n`。 由于所有 IP 地址都是不同的，因此 32 位掩码始终会生成`n`不同的网络地址。 忘记考虑全长掩码的解决方案将错误地报告`-1`。 

例子：```
2 2
1.1.1.1
1.1.1.2
```正确答案是：```
255.255.255.255
```当没有掩模准确产生时会发生另一种微妙的情况`k`组。 

例子：```
2 1
0.0.0.0
255.255.255.255
```对于任何有效的子网掩码，这些地址仍位于不同的网络中。 正确的输出是：```
-1
```第三个陷阱是选择了错误的有效掩码。 没有人要求我们提供任何口罩。 我们必须归还数量最少的那一个。 

例子：```
2 1
1.2.3.4
1.2.3.5
```两个都`/31`和`/30`产生一个网络，但答案一定是`/30`因为它的一位较少。 

## 方法

 蛮力的想法很简单。 子网掩码完全由其前缀长度决定。 如果我们需要至少一个，则只有 31 个有效掩码`1`一点并且至少一个`0`位，或者如果我们考虑保持 0 到 32 个前导位，则相当于 33 种可能性。 对于每个掩码，计算每个网络地址并计算出现的不同结果的数量。 

一个口罩的费用是`O(n)`。 对所有可能的前缀长度重复此操作会产生成本`O(32n)`，这大约是 320 万次操作`n = 100000`。 令人惊讶的是，这已经足够快了。 

关键的观察是搜索空间很小。 尽管输入最多包含十万个地址，但子网掩码的数量受到 IP 地址位宽（即 32）的限制。 

第二个观察结果使解决方案更加清晰。 随着前缀长度的增加，每个地址的更多位被保留。 网络只能分裂，不能合并。 因此，不同网络地址的数量相对于前缀长度是单调的。 

如果我们定义：`f(p) = number of distinct networks using the first p bits`然后`f(p)`永远不会减少`p`成长。 

这种单调性允许二分搜索。 我们可以找到网络数至少为 的最小前缀长度，而不是检查所有 33 个前缀长度`k`。 

一旦找到前缀长度，我们只需验证计数是否准确`k`。 如果不是，则不存在解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(32n) | O(32n) | O(n) | 已接受 |
 | 最佳 | O(n log 32) = O(n) | O(n log 32) = O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将每个点分IP地址转换为32位整数。 

整数上的位运算比字符串上的位运算简单得多。 
2. 定义函数`count_networks(p)`。 

该函数只保留第一个`p`每个地址的位并计算剩余的不同结果的数量。 
3. 对于前缀长度`p`，构造相应的掩码。 

如果`p = 0`，掩码全为零。 

否则：`mask = ((1 << p) - 1) << (32 - p)`4. 将掩码应用于每个地址并将结果插入到集合中。 

集合大小等于不同网络的数量。 
5. 二分查找`p`从`0`到`32`。 

因为网络的数量永远不会随着保留更多位而减少，所以谓词`count_networks(p) >= k`is monotonic.
 6. 求最小前缀长度`p`为此`count_networks(p) >= k`。 

这是产生最少一位的候选者。 
7. 计算`count_networks(p)`再次。 

如果结果不准确`k`，不存在有效的子网掩码，我们打印`-1`。 
8. 否则转换对应的掩码`p`返回点分十进制表示法并打印。 

### 为什么它有效

 对于任何前缀长度`p`，两个 IP 地址在它们的第一个 IP 地址完全相同时属于同一网络`p`位是相同的。 增加`p`使用附加位来区分地址，因此现有组可能会分裂，但永远不能合并。 因此，不同网络的数量是单调的。 

二分查找找到网络数至少达到的最小前缀长度`k`。 如果该计数等于`k`，我们找到了具有最少一位的有效掩码，因为每个较小的前缀长度产生的少于`k`网络。 如果计数大于`k`，单调性意味着没有前缀长度可以精确产生`k`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ip_to_int(s):
    a, b, c, d = map(int, s.strip().split('.'))
    return (a << 24) | (b << 16) | (c << 8) | d

def mask_from_prefix(p):
    if p == 0:
        return 0
    return ((1 << p) - 1) << (32 - p)

def count_networks(ips, p):
    mask = mask_from_prefix(p)
    return len({ip & mask for ip in ips})

def int_to_ip(x):
    return ".".join(str((x >> shift) & 255) for shift in (24, 16, 8, 0))

def solve():
    n, k = map(int, input().split())

    ips = [ip_to_int(input()) for _ in range(n)]

    left, right = 0, 32

    while left < right:
        mid = (left + right) // 2

        if count_networks(ips, mid) >= k:
            right = mid
        else:
            left = mid + 1

    p = left

    if count_networks(ips, p) != k:
        print(-1)
        return

    print(int_to_ip(mask_from_prefix(p)))

solve()
```第一个助手将点分符号转换为单个 32 位整数。 这让我们可以直接使用位掩码而不是操作字符串。`mask_from_prefix`构造与前缀长度对应的子网掩码。 特殊情况`p = 0`是必要的，因为否则移位 32 位需要格外小心。`count_networks`将掩码应用于每个地址并将结果存储在一个集合中。 该集合的大小正是不同网络的数量。 

二分搜索利用网络计数的单调性。 当前缀长度已经至少产生`k`网络，任何更大的前缀长度也将产生至少`k`，所以我们向左移动。 否则我们向右移动。 

二分查找结束后，得到计数达到的最小前缀长度`k`。 我们仍然必须验证相等性，因为计数可能会从小于`k`直接大于`k`。 

最后，通过提取四个字节，将掩码转换回点分符号。

 ## 边缘情况

 考虑：```
1 1
5.6.7.8
```对于前缀长度`0`，每个地址都映射到网络`0`。 由于只有一个地址，因此网络数量已经是`1`。 二分查找返回`p = 0`，生产口罩`0.0.0.0`。 这是正确的最小一位解决方案。 

考虑：```
2 1
0.0.0.0
255.255.255.255
```前缀长度从`0`通过`31`，地址保留在不同的组中，因为它们的最高位已经不同。 计数永远不会变成`1`，因此二分查找在计数仍大于的前缀处结束`1`。 最终的相等性检查失败并且算法打印`-1`。 

考虑：```
2 1
1.2.3.4
1.2.3.5
```计数演变为：

 | 前缀 | 网络|
 | --- | --- |
 | 29 | 29 1 |
 | 30| 1 |
 | 31 | 2 |

 实现一个网络的最小前缀是`30`。 该算法有意搜索最小的有效前缀，保证掩码包含最少的一位。
