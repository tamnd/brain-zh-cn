 ## 解决方案
 ## 问题理解

 我们被要求构造尽可能大的数字，其数字之和等于给定的总和`n`，有两个限制：数字不能包含零，并且连续的两个数字不能相等。 每个测试用例提供不同的总和`n`，并且我们必须为每个生成一个有效的数字。 输入由最多 1000 个测试用例组成，每个测试用例都包含`1 ≤ n ≤ 1000`。 输出是满足约束的最大数量。 

一种简单的方法可能会尝试生成所有数字序列，总和为`n`，过滤掉那些有零或重复的连续数字，然后对它们进行数值比较。 这很快就变得不可行：对于`n = 1000`，数字序列的数量是天文数字，远远超过 1 秒时间限制的任何合理操作计数。 因此，我们需要一种建设性的方法，直接构建数字而不是枚举可能性。 

可能导致粗心实施的边缘情况包括小`n`单位数字答案是最佳的值，以及在数字之间交替以最大化前导数字的序列。 例如，`n = 1`应该产生`1`， 和`n = 11`应该产生`987`而不是尝试使用重复的数字，例如`5551`，这将违反连续数字规则。 

## 方法

 暴力方法生成每个数字序列，总和为`n`，过滤掉包含零个或重复的连续数字的序列，并选取最大值。 虽然概念上很简单，但这种方法的效率呈指数级增长`n`，因为长度达到的序列数`n`组合增长。 和`n`高达 1000 时，暴力方法无法在任何合理的时间内完成。 

关键的见解是，如果最左边的数字尽可能大，并且连续数字不同，则数字最大。 我们可以通过使用从 9 到 1 的降序序列从右到左重复构建数字来利用这一点，并减去每个数字`n`直到我们达到零。 在末尾反转构造的序列可确保最大的数字首先出现。 此方法之所以有效，是因为可用的最大数字始终放置在使总数最大化的位置，而降序模式自然可以防止连续重复。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.初始化一个空列表`digits`存储我们正在构造的数字。 
2. 从尽可能大的数字开始`9`。 尽管`n`大于零，检查当前数字是否可以使用而不超过`n`。 
3. 将当前数字附加到`digits`，并从中减去它的值`n`。 减少下一次迭代的数字。 如果该数字变为零，请将其重置为 9 以继续序列。 
4. 重复此过程直至`n`达到零。 
5. 反转`digits`并将它们连接成一个字符串以产生最终的数字。 

这是有效的，因为我们总是首先取最大的可用数字，最初将其放置在最不重要的位置，然后反向将其移动到最重要的位置。 降序序列可以防止连续重复，并且仅使用数字 1-9 可以完全避免零。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        digits = []
        current = 9
        while n > 0:
            take = min(current, n)
            digits.append(take)
            n -= take
            current -= 1
            if current == 0:
                current = 9
        print("".join(map(str, reversed(digits))))

solve()
```该函数读取测试用例的数量并迭代每个测试用例`n`。 这`while`循环从 9 向下贪婪地构造数字，必要时环绕到 9。 最终的数字是通过反转数字列表来构建的，确保较大的数字占据更重要的位置。 精心处理`current`确保没有连续的重复项，也没有出现零。

 ## 边缘情况

 对于`n = 1`，算法立即选择`1`，生产`1`。 不存在连续的重复项或零，满足约束条件。 为了`n = 20`，序列`[9,8,3]`被迭代选择。 反转产生`389`，将最大的数字放在最重要的位置。 该算法在必要时回绕，从不违反连续数字规则。 这些痕迹证实该构造可以处理最小和大的总和，总是产生最大的有效数。
