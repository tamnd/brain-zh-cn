 ## 解决方案
 ## 问题理解

 我们得到一个从 1 到 6 的数字序列，并且允许我们将任何元素更改为 1 到 6 之间的任何其他值。目标是转换该序列，以便每对相邻元素的行为就像标准骰子上的有效转换一样。 

标准模具可以被认为具有配对的相对面，如 (1,6)、(2,5)、(3,4)。 如果任何两个数字不相等并且面不相对，则认为它们是相邻的。 因此，从任何面来看，都恰好有四个有效邻居。 

我们希望对数组进行最小程度的修改，以便每个连续的对在某些面分配下都满足此邻接规则。 

关键的困难是我们没有独立选择过渡。 在位置 i 分配的值必须与其上一个和下一个邻居选择一致，这会创建一个全局一致性约束，类似于沿着图行走，同时最小化节点更改。 

约束条件很大，测试用例的总 n 高达 3⋅10^5。 这立即排除了每个测试用例的任何二次方。 任何解决方案在总输入大小上都必须是线性或接近线性的。 具有恒定状态的每个位置 DP 是合理的。 

一个微妙的边缘情况是局部贪婪选择失败。 例如，如果我们总是在每一步中选择最好的有效邻居，我们可能会将自己陷入一个角落，如果不进行额外的更改，后面的位置将无法匹配。 这通常发生在诸如交替不兼容的强制转换之类的序列中，其中早期决策会降低未来的灵活性。 

## 方法

 如果我们尝试暴力破解，我们会将每个位置视为从 1 到 6 之间选择一个值，并确保邻居之间的邻接约束。 这本质上是计算所有有效序列的最小不匹配数。 一种简单的方法是尝试每个位置的所有 6 个选择，给出 6^n 个序列，这在 n = 20 之外是完全不可行的。 

我们可以将问题重新定义为位置的动态规划。 在每个索引 i 处，我们决定最终的值，如果它与原始 a[i] 不同，我们就要付出代价。 仅当两个值在立方体上相邻时，才允许 i−1 和 i 之间的转换。 

这将创建一个分层图：每个位置有 6 个状态，有效相邻面之间存在边。 我们想要一条从第 1 层到第 n 层的最小成本路径。 

关键的观察结果是立方体结构是固定的并且非常小。 每个面恰好有 4 个邻居，因此转换是恒定时间的。 这将问题简化为具有 O(n⋅6) 状态和每个状态恒定转换的 DP 问题。 

我们还避免了贪婪的错误，因为 DP 同时进行所有可能的最后面选择，确保我们永远不会放弃以后可能是最佳的路径。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(6^n) | O(6^n) | O(n) | 太慢了|
 | 最佳DP | O(n) | O(n) 或 O(1) | 已接受 |

 ## 算法演练

 如果我们将最终序列中的 a[i] 设置为值 x，我们将 dp[i][x] 定义为索引 i 之前的前缀所需的最小更改次数。 

1. 如果 x 等于 a[1]，则将 1 到 6 中所有 x 的 dp[1][x] 初始化为 0，否则为 1。 

这表示选择第一个值并在覆盖它时付出代价。 
2. 对于从 2 到 n 的每个位置 i，计算从 1 到 6 的所有 x 的 dp[i][x]。 

每个状态代表强制位置 i 变为值 x。 
3. 对于位置 i 处的每个候选值 x，考虑所有先前值 y，使得 y 与立方体上的 x 相邻。 

我们只允许从有效的骰子邻接进行转换，因为无效的骰子对会破坏序列。 
4. 将 dp[i][x] 设置为 dp[i−1][y] + cost(i, x) 的所有有效 y 的最小值，其中如果 a[i] ≠ x，则 cost(i, x) 为 1，否则为 0。

这确保我们同时考虑转换有效性和修改成本。 
5. 答案是 x 从 1 到 6 的所有 dp[n][x] 中的最小值。 

核心思想是，在每一步中，我们都维护所有可能的最后面配置，并且只向前传播有效的立方体移动。 

### 为什么它有效

 在每个位置 i，DP 状态充分总结了构造以特定面 x 结尾的前缀的所有有效方法。 任何有效的完整序列必须恰好对应于通过这些状态的一条路径。 由于过渡仅允许相邻的立方体面，因此每个 DP 过渡都会保留骰子条件的有效性。 由于我们尝试了所有可能的先前有效状态并采用最小成本，因此在任何步骤都不能排除全局最优配置。 

这是分层图上的标准最短路径，其中节点是（位置、面）对，边表示单位成本或零成本的有效立方体转换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# adjacency list for a standard die
adj = {
    1: [2, 3, 4, 5],
    2: [1, 3, 6, 4],
    3: [1, 2, 6, 5],
    4: [1, 2, 6, 5],
    5: [1, 3, 6, 4],
    6: [2, 3, 4, 5]
}

INF = 10**9

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    dp_prev = [INF] * 7
    dp_cur = [INF] * 7

    for x in range(1, 7):
        dp_prev[x] = 0 if a[0] == x else 1

    for i in range(1, n):
        for x in range(1, 7):
            best = INF
            cost = 0 if a[i] == x else 1
            for y in adj[x]:
                best = min(best, dp_prev[y])
            dp_cur[x] = best + cost

        dp_prev, dp_cur = dp_cur, [INF] * 7

    print(min(dp_prev[1:]))
```DP 使用两个滚动数组来实现，因为每一步只需要前一行。 邻接列表对立方体几何图形进行显式编码，确保过渡正确。 

一个常见的错误是反转转换的方向，但由于这里的邻接是对称的，因此迭代前一个状态中 x 的邻居仍然可以正确捕获所有有效的转换。 另一个微妙之处是为第一个元素正确初始化 dp，其中尚不存在转换约束。 

## 工作示例

 ### 示例 1

 输入：```
3
1 4 2
```我们将 dp 初始化为 i = 1：

 | 脸 x | 成本|
 | ---| ---|
 | 1 | 0 |
 | 2 | 1 |
 | 3 | 1 |
 | 4 | 0 |
 | 5 | 1 |
 | 6 | 1 |

 在 i = 2 和 i = 3 时，转换始终保持可行，无需更改，因此成本保持为 0。序列已经尊重立方体邻接，因此 DP 传播零成本路径。 

这证实了 DP 正确地保留了有效的现有序列，而没有强制进行不必要的更改。 

### 示例 2

 输入：```
3
3
3 4 6 3
```我们仅跟踪相关状态：

 | 我| 选择x | 以前最好的 y | 成本| dp[i][x] | dp[i][x] |
 | ---| ---| ---| ---| ---|
 | 1 | 3 | - | 0 | 0 |
 | 2 | 4 | 4 的有效邻居包括 3 | 0 | 0 |
 | 3 | 6 | 必须来自 6 | 的有效邻居 0 | 0 |
 | 4 | 3 | 过渡可能需要调整| 1 | 1 |

 在最后一步，强制有效的延续需要更改一个元素。 DP 认为最佳路径需要进行一次修改，而不是在本地修复早期步骤。 

这说明了贪婪修复失败的原因：如果不重新审视早期的选择，局部有效性并不能保证全局可行性。 

## 复杂度分析

 ## 边缘情况

 一个棘手的情况是当序列包含不是有效转换的重复值时，例如`[1,1,1,1]`。 DP 通过强制通过有效邻居进行转换来处理此问题，因此每次重复都会产生成本，除非它可以映射到有效的相邻面路径。 该算法自然地选择一致的面部分配来最小化变化，而不是反复尝试保留无效的相等邻接。 

另一种情况是长度为 2 的短序列，其中该对是相对的面，例如`[1,6]`。 由于 1 和 6 不相邻，因此至少有一个必须改变。 DP 正确评估了两种可能性并选择成本 1。 

例如，当局部最优转换没有扩展到全局时，就会出现更微妙的情况`[3,4,6,3]`。 仅修复一个中间元素就足够了，但贪婪方法可能会错误地尝试修复多个位置。 DP 同时正确评估所有路径并找到单一更改解决方案。
