 ## 解决方案
 ## 问题理解

 我们得到一棵有根二叉树，其中每个顶点要么恰好有两个子节点，要么是叶子。 根是顶点 0，所有其他顶点编号从 1 到 n。 一个进程从某个顶点 v 开始，并根据非常具体的状态规则逐步移动。 

每个顶点存储三个可能的标记之一：空、L 或 R。最初所有顶点都是空的。 当鲍勃站在一个顶点上时，他的下一步行动取决于树的结构以及之前在该顶点上写入的内容。 如果当前顶点是叶子，他总是移动到其父节点。 否则，顶点就像一个微小的三态自动机。 第一次访问写入 L 并向左移动，第二次访问覆盖 R 并向右移动，第三次访问擦除并将其向上发送给父级。 之后，循环重复。 

对于许多查询，我们被要求模拟从给定顶点 v 开始的恰好 k 次移动的过程，但保证 k 严格小于逃逸到根所需的时间。 因此，我们实际上从未达到顶点 0 处的吸收状态，这消除了与终止相关的复杂性。 

约束很大：总共最多 3e5 个顶点和 4e5 个查询。 一个简单的模拟每次移动都会更新树状态，每次查询需要 O(k)，并且由于 k 可以大到 1e9，所以这是完全不可行的。 即使是完整的每个查询模拟也是不可能的，因为查询是独立的，但在树上共享相同的隐式无限状态机。 

一个微妙的边缘情况是该过程不是简单的遍历。 一个顶点可以被多次访问，其外出方向取决于循环局部状态。 例如，从左子节点是叶子的节点开始，第一次访问会强制向左移动，但下次访问同一节点时，方向会完全改变。 天真的 DFS 直觉会被打破，因为路径不固定。 

另一种失效模式是假设朝根部单调移动或始终以可预测的模式左右交替。 “擦除到父级”步骤引入了回溯，回溯取决于节点被访问的次数，这取决于完整的历史记录，而不仅仅是当前位置。 

## 方法

 直接模拟维护每个节点的状态并为每个查询执行 k 个转换。 每次转换都是 O(1)，但 k 可以达到 1e9，因此最坏情况的复杂度变为 O(q·k)，这远远超出了限制。 

即使我们尝试以固定状态缓存来自每个节点的转换，困难在于节点的状态不仅是本地的，而且取决于在当前执行中被访问的次数。 不同的查询从不同的节点开始，因此不存在全局共享状态演化。 

关键的观察结果是，尽管全局状态不断变化，但每个顶点在被访问时都会遵循确定性的三相循环。 这意味着可以将行为建模为沿树边缘重复的结构化游览：从一个节点开始，Bob 重复向下到子节点，直到碰到叶子，然后向上返回，并且这些游览以类似于欧拉游览的模式重复，不同之处在于方向决策取决于访问奇偶校验模 3。 

如果我们从每个节点开始，但只到返回根变得相关的点，我们就预先计算过程的整个确定性遍历顺序，而不是模拟移动。 这导致将该过程解释为在隐式有向图上行走，其节点是对（顶点、状态），其中状态是 0、1、2 表示空、L、R 转换。

关键的简化是每个查询都要求在此扩展状态图上确定性行走的前缀。 由于 k 小于逃逸时间，我们永远不会到达终端节点 0，这意味着我们停留在图的循环部分内。 因此，我们可以在此状态图中使用二进制提升随时间步长来预处理跳转指针。 

我们构建一个转换函数 nxt[v][s]，它给出一次移动后的下一个（顶点，状态）。 然后我们构造二进制提升表，这样我们就可以在 O(log n) 的时间内跳转 k 步。 

困难在于高效构建 nxt，而无需显式存储所有访问的所有状态。 我们利用转换仅依赖于局部状态模 3，并且子结构是固定的，因此可以通过独立处理每个顶点来在 O(n) 中计算 nxt。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(q·k) | O(n) | 太慢了|
 | 状态图+二值提升| O((n + q) log n) | O((n + q) log n) | O(n log n) | O(n log n) | 已接受 |

 ## 算法演练

 我们将每个顶点 v 建模为具有三个内部状态，表示它在当前周期中已被使用的次数。 我们定义一个函数，给定 (v, state)，返回一次移动后的下一个位置。 

1.我们为每个顶点定义状态0、1、2，分别表示空、L、R行为。 这准确地编码了节点在重复访问时如何改变行为，从而消除了动态修改树的需要。 
2. 对于每个（v，状态），我们使用树结构显式计算下一个位置。 如果 v 是叶子，则无论状态如何，下一个顶点都是其父顶点。 这是强制逃脱规则。 
3. 如果 v 不是叶子，我们遵循以下规则：

 如果 state 为 0，我们转到左子节点并将 state 更新为 1；

 如果 state 为 1，我们转到右子节点并将 state 更新为 2；

 如果状态为 2，我们转到父级并将状态重置为 0。 

这完全编码了本地自动机，而不修改全局内存。 
4. 我们构建一个包含 3(n+1) 个状态的有向图，每个节点只有一个出边。 这形成了一个函数图。 
5. 对于每个状态，我们使用重复加倍转换来预先计算二进制提升祖先到 log K。 每个步骤都构成函数图中的转换。 
6. 对于每个查询 (v, k)，我们将其映射到初始状态 (v, 0) 并应用二进制提升来沿函数图移动 k 步。 
7. 我们输出结果状态的顶点分量。 

### 为什么它有效

 关键的不变量是，一旦编码为（顶点，状态），整个过程就是无记忆的。 每一步行动仅取决于这对货币对，而不取决于全球历史。 因此，演化标签的原始过程相当于在大小为 3(n+1) 的固定有向图上进行确定性行走。 由于每个查询都要求从给定节点开始的此行走的前缀，因此二进制提升无需模拟即可正确计算 k 次转换后的确切位置。 没有任何步骤依赖于编码状态之外的信息，因此正确性来自于转换系统的等价性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

LOG = 20

def solve():
    n, q = map(int, input().split())
    l = [0] * (n + 1)
    r = [0] * (n + 1)
    par = [0] * (n + 1)

    for i in range(1, n + 1):
        li, ri = map(int, input().split())
        l[i], r[i] = li, ri
        if li:
            par[li] = i
        if ri:
            par[ri] = i

    # state id: v * 3 + s
    N = (n + 1) * 3

    def id(v, s):
        return v * 3 + s

    nxt = [0] * N

    for v in range(n + 1):
        for s in range(3):
            if v == 0:
                nxt[id(v, s)] = id(v, s)
                continue

            if l[v] == 0 and r[v] == 0:
                nxt[id(v, s)] = id(par[v], 0)
                continue

            if s == 0:
                to = l[v]
                ns = 1
            elif s == 1:
                to = r[v]
                ns = 2
            else:
                to = par[v]
                ns = 0

            nxt[id(v, s)] = id(to, ns)

    # binary lifting
    up = [[0] * N for _ in range(LOG)]
    for i in range(N):
        up[0][i] = nxt[i]

    for k in range(1, LOG):
        prev = up[k - 1]
        cur = up[k]
        for i in range(N):
            cur[i] = prev[prev[i]]

    for _ in range(q):
        v, k = map(int, input().split())
        cur = id(v, 0)
        for i in range(LOG):
            if k & (1 << i):
                cur = up[i][cur]
        print(cur // 3)

if __name__ == "__main__":
    solve()
```该实现在扩展状态上构建显式转换图，然后应用标准二进制提升。 微妙之处在于，每个节点状态对都被视为确定性机器状态，因此我们从不存储可变的每个节点标签。 相反，状态演化被吸收到图结构本身中。 最后除以 3 可从编码状态恢复顶点索引。 

一个常见的陷阱是错误地处理 0 的父级或叶子不一致； 这里顶点 0 被设置为吸收的，以便转换永远不会离开它，这与查询保证 k 严格在到达 0 之前的事实相匹配。 

## 工作示例

 考虑一棵小树，其中 1 有子树 2 和 3，并且 2 和 3 都是叶子。 假设我们从状态 0 的顶点 1 开始。 

| 步骤| （v，状态）| 行动| 下一个（v，状态）|
 | ---| ---| ---| ---|
 | 1 | (1,0)| 向左走| (2,1) |
 | 2 | (2,1) | 叶→父| (1,0)|
 | 3 | (1,0)| 向左走| (2,1) |
 | 4 | (2,1) | 叶→父| (1,0)|

 这表明由于叶子规则覆盖本地状态行为，进程在父进程和叶子进程之间振荡。 

现在考虑从具有本身内部的右子节点的节点开始。 从 (1,0) 开始：

 | 步骤| （v，状态）| 行动| 下一页 |
 | ---| ---| ---| ---|
 | 1 | (1,0)| 左| (L,1) |
 | 2 | (L,1) | 叶或内部取决于 | ... |

 这表明序列完全取决于编码的转换，而不是固定的遍历顺序。 

这些示例证实，将每个顶点状态对表示为确定性节点可以保留原始过程的精确动态。
