 ## 解决方案
 ## 问题理解

 我们给出了从 1 到 n 的整数排列，并且可以执行特定类型的交换：对于从 1 到 n/2 的任何索引 i，我们可以将位置 i 处的元素与位置 2i 处的元素交换。 任务是确定通过执行任意次数的此类交换，数组是否可以按升序排序。 

输入代表多个测试用例。 每个测试用例给出一个整数 n，即排列的长度，后跟 n 个以任意顺序从 1 到 n 的不同整数。 如果可以使用允许的操作对数组进行排序，则每个测试用例的输出为“YES”，否则为“NO”。 

限制很重要：n 最多可以为 200,000，测试用例最多可以有 10,000 个，但所有测试用例的 n 总和限制为 200,000。 这意味着我们需要为每个测试用例提供一个关于 n 的线性或近线性解。 模拟所有可能交换的简单方法将在 n 中呈指数增长并且完全不可行。 

当数组几乎已排序（除了由于 2i 交换结构而无法到达其目标位置的元素之外）时，就会出现边缘情况。 例如，对于n=5，如果排列是[1,4,2,3,5]，则索引2处的元素4可以与索引4处的2交换，允许排序，所以答案是YES。 但如果数组是 [1,4,2,3,5]，则通过交换可到达的位置不允许元素 4 移动到索引 4 处的正确位置，因此答案是否定的。 忽略交换图结构的简单算法可能会错误地回答“是”。 

## 方法

 暴力方法是模拟允许交换的每个可能的序列，并检查数组是否可以排序。 每次交换仅影响位置对 (i, 2i)，但有许多可能的交换序列。 对于 n=200,000，序列的数量是天文数字。 即使在所有组合中执行每次交换也是不切实际的，因为操作计数会呈指数增长。 

关键的见解是将允许的交换建模为有向图：索引 i 可以达到索引 2i，反之亦然，因为交换是可逆的。 这形成了一个以索引为根的树木森林，这些索引不能写成 i=2j（通常是最后一个索引）。 关键的观察是元素只能在这些交换定义的索引的连接组件内移动。 一旦知道了连接的组件，您就可以检查每个组件是否恰好包含应占据排序数组中这些位置的元素。 当且仅当每个组件包含这些位置的正确目标值多重集时，排序才是可能的。 

因此，最佳方法是识别交换关系下索引的连通分量，并将每个分量中的元素集与它们占据的排序位置集进行比较。 该方法以相对于 n 的线性时间运行，因为每个索引都被访问一次，并且组件成员资格检查是线性的。

 ## 算法演练

1. 对于每个测试用例，读取 n 和排列数组 a。 
2. 初始化一个长度为 n 的布尔访问数组来跟踪哪些索引已被处理。 
3、对于从1到n的每个索引i，如果没有被访问过，则启动一个新的组件。 初始化两个空列表：一个用于此组件中的索引，另一个用于这些索引处的元素。 
4. 使用深度优先搜索或迭代遍历来收集通过交换从 i 可达的所有索引。 对于访问过的每个索引 j，将其标记为已访问，将 j 添加到索引列表，并将 a[j] 添加到元素列表。 对于每个索引，考虑 j → 2j 和 2j → j 连接，只要索引保持在界限内。 
5. 收集组件后，对索引列表和元素列表进行排序。 按元素比较两个列表； 索引列表表示必须包含某些数字的位置，元素列表表示实际位于这些位置的数字。 如果它们不同，则无法排序。 
6. 如果所有组件都符合其预期元素，则打印 YES； 否则，打印NO。 

为什么有效：交换操作定义了索引的连接组件，这些组件可以在它们之间自由交换元素。 每个组件都是独立的，因此不同组件中元素的相对顺序不能更改。 仅当每个组件完全包含其在最终排序数组中的位置所需的元素时，才可以对数组进行排序。 该算法直接检查这个不变量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

def can_sort_heapify(n, a):
    visited = [False] * n

    def dfs(idx, indices):
        visited[idx] = True
        indices.append(idx)
        for nxt in [2*(idx+1)-1, (idx+1)//2-1]:
            if 0 <= nxt < n and not visited[nxt]:
                dfs(nxt, indices)

    for i in range(n):
        if not visited[i]:
            indices = []
            dfs(i, indices)
            component_values = [a[j] for j in indices]
            if sorted(indices) != sorted([v-1 for v in component_values]):
                return "NO"
    return "YES"

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(can_sort_heapify(n, a))
```该解决方案首先设置足够高的递归限制以避免大 n 的堆栈溢出。 DFS 探索通过允许的交换可到达的所有索引，形成连接的组件。 对于每个组件，我们提取当前元素和这些位置的目标排序值。 对两个列表进行排序并进行比较可确保可以在组件内重新排列元素以匹配排序后的数组。 使用基于 0 的索引可简化 DFS 和数组处理。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个索引在 DFS 中只被访问一次； 对每个组件进行排序的时间复杂度为 O(k log k)，但所有组件的 k 总和为 n，因此最坏情况为 O(n log n) |
 | 空间| O(n) | 访问数组和DFS堆栈|

 给定 n ≤ 2⋅10^5 且 t ≤ 10^4，并且测试中的总 n ≤ 2⋅10^5，该解决方案很容易满足时间和内存限制。
