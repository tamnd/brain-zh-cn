 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，并且允许我们删除字符，但有一个限制：任何删除的位置都不能与原始字符串相邻。 删除一些选定的字符后，我们连接剩余的字符并获得更短的字符串。 

问题是我们是否可以执行这样的删除，以便结果字符串按非递减顺序排序，这意味着所有零都在所有一之前，没有像这样的模式`10`出现在最后的字符串中。 

关键的微妙之处在于我们没有重新排列字符，只是删除其中一些字符，并且删除不能发生在相邻索引上。 所以我们可以“稀疏”字符串，但永远不要同时占据两个相邻的位置。 

约束条件`|s| ≤ 100`足够小，每次测试的 O(n²) 甚至 O(n³) 想法都是可以接受的。 对于多达 1000 个测试用例，我们仍然预计总共最多大约 10^5 个字符，因此每个测试的线性或二次扫描是安全的。 任何指数级的头寸都会有风险，但我们在这里不需要它。 

一个天真的错误是假设我们只需要检查字符串是否已经没有`10`过渡。 这是错误的，因为删除可以消除有问题的结构。 例如，`1100`未排序，但删除中间`0`或者`1`适当地可以使其排序。 另一个常见的失败是忽略非邻接约束：它阻止我们任意删除一个区域中的所有“坏”字符。 

更隐藏的边缘情况是交替模式，例如`101010`，在本地看起来很灵活，但邻接限制阻止清除所有反转。 

## 方法

 暴力视图是尝试所有有效的删除集：选择没有两个连续的索引子集，模拟结果字符串，并检查它是否已排序。 每个子集对应于每个位置的二元决策，但限制是我们不能选择相邻的决策。 

这导致有效子集大致呈斐波那契式增长，大约为 O(φ^n)，但仍然呈指数增长。 即使 n = 100，这也是不可行的。 

关键的观察是转变视角：不要考虑我们删除哪些位置，而是考虑我们是否可以消除该模式的所有出现`10`在结果字符串中。 当字符串不存在时，它被精确排序`1`随后是`0`。 

所以每一个坏对都由一个`1`出现在 a 之前`0`幸存下来。 为了解决这个问题，对于每个这样的反转，我们必须删除至少两个涉及的位置之一。 但删除不能相邻，因此我们不能自由选取附近反转的两个端点。 

这变成了一个经典的贪婪约束：我们从左到右扫描，每当我们检测到强制冲突的转换时，我们就决定是否删除一个字符，同时尊重删除的邻接性。 关键的简化是我们只需要确保我们永远不会“保留”`1`当我们决定保留一个`0`稍后出现在最终结构中。 这导致了贪婪的可行性检查，我们模拟构建最终的字符串，同时跟踪我们是否已经开始看到零以及是否仍然允许零。 

对于这个问题的一个更具体的简化是：只有当存在一个`0`它受到周围的“太多限制”，以至于我们无法在不违反非相邻删除的情况下消除所有倒置。 这减少为单个线性扫描，以维持不良配置是否不可避免。

 ## 算法演练

 我们独立处理每个字符串，并模拟是否可以使用有效删除将其转换为排序序列。 

1. 从左到右扫描字符串，同时跟踪我们是否已经“承诺”在后缀结构中保留零。 这很重要，因为一旦`0`实际上是在最后的后缀中，更早`1`这会成为问题。 
2. 维护一个标志，指示我们是否已经看到`0`必须出现在未来之前`1`s 在任何有效的排序结果中。 在排序的二进制字符串中，所有零都必须出现在零之前，因此一旦出现零，只有当我们可以提前删除足够多的冲突零时，才允许在零之后出现零。 
3.当我们遇到一个`1`当我们已经建立了一个“零区域”后，我们检查是否可以通过删除来消除它而不违反非邻接规则。 如果这种冲突累积到超出了当地能够解决的范围，我们就认为这是不可能的。 
4. 核心决策简化为检查是否存在每个反演对都存在的配置`10`可以通过删除至少一个端点来破坏，而无需强制两个相邻的删除。 如果在任何时候我们被迫删除相邻索引来修复多个重叠反转，我们将返回“NO”。 
5. 如果我们完成扫描而没有遇到不可避免的冲突，则答案为“是”。 

### 为什么它有效

 该算法将所有约束编码为有关反演的局部决策。 每个未排序的二进制字符串的特征是出现`1`前`0`。 任何有效的转换都必须打破所有这些对。 非邻接规则限制了删除自由度，但由于每个冲突在结构上都是局部和线性的，因此任何全局障碍都表现为我们需要两个相邻删除来修复重叠反转约束的点。 检测到该点就足以保证正确性，因为所有其他配置都可以独立解析。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve(s: str) -> str:
    n = len(s)
    
    # We track whether we have seen a '0' that is forced to be in the final structure
    seen_zero = False
    
    # We track a local conflict counter: how many "1 before 0" tensions exist
    # that would require deletions in overlapping regions
    conflict = 0
    
    for i, ch in enumerate(s):
        if ch == '0':
            seen_zero = True
            # zeros reinforce the requirement that future ones are problematic
        else:
            if seen_zero:
                # this 1 appears after a 0, contributing to inversion pressure
                conflict += 1
                
                # if conflicts pile up too much, we'd need adjacent deletions
                if conflict >= 2:
                    return "NO"
    
    return "YES"

def main():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        print(solve(s))

if __name__ == "__main__":
    main()
```该解决方案依赖于对字符串的单次传递。 这`seen_zero`标志标记零何时开始约束结构，并且每个`1`之后压力会增加，因为它参与了潜在的反转。 

关键的实现选择是我们不显式模拟删除。 相反，我们检测结构何时需要解决多个重叠`10`冲突，这将强制删除相邻的内容，从而违反了规则。 门槛`conflict >= 2`抓住了不可约性点。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve(s: str) -> str:
        seen_zero = False
        conflict = 0
        for ch in s.strip():
            if ch == '0':
                seen_zero = True
            else:
                if seen_zero:
                    conflict += 1
                    if conflict >= 2:
                        return "NO"
        return "YES"

    t = int(input())
    out = []
    for _ in range(t):
        out.append(solve(input().strip()))
    return "\n".join(out)

 ## 边缘情况

 像这样的字符串`10`是单个删除可以修复排序的最小非平凡情况，并且它证实了算法不会过于激进地拒绝。 交替字符串如`1010`或者`0101`强调重叠反转逻辑，其中每个角色都参与多个冲突对。 统一字符串，例如`0000`和`1111`总是可简单排序，并确认当不存在反转时扫描不会引入假阴性。
