 ## 解决方案
 ## 问题理解

 我们从一个二部图开始，其边到达在线。 每条边最终必须分配两个标签之一：红色或蓝色。 对于任何顶点，我们比较红色和蓝色的入射边的数量，并支付这两个计数的绝对差。 目标是保持所有当前现有边的着色，从而最大限度地减少所有顶点之间的总不平衡。 

每次插入边缘后，我们都会被要求输出一个代表某些最佳着色的“散列”的数字。 后来，有时，我们必须重建与之前报告的哈希相对应的实际最佳着色。 

关键的困难不是目标本身，它是每个顶点局部的，而是两个方面的结合：图在线增长到 200,000 条边，而且我们还必须能够从它的压缩表示中重现一致的最优解。 

这些约束已经排除了所有边缘上的任何每次查询重新计算。 在最坏的情况下，即使每次更新进行线性时间重新计算也会导致大约 4e10 次操作。 这迫使形成一个完全增量的结构，其中每个新边仅稍微修改状态。 

一个微妙的边缘情况来自这样一个事实：目标仅取决于每个顶点的度数，但哈希取决于边缘索引。 一个天真的想法是根据端点贪婪地独立决定每个边缘颜色，但这失败了，因为选择通过顶点的奇偶约束相互作用。 另一种失败模式是每次重新计算最佳着色，但忘记后来的重建必须匹配精确的散列，这迫使多个最佳解决方案的选择方式保持一致。 

## 方法

 目标在顶点上分解，这建议查看单个顶点更喜欢什么。 对于度数为 d 的顶点，贡献 |r(v) - b(v)| 当入射边缘在两种颜色之间尽可能均匀地分割时，该值最小化。 如果 d 是偶数，则可以实现完美平衡。 如果 d 为奇数，则正好有一条边“不成对”，并且对不平衡贡献 1。 

这将全局问题转化为每个顶点处的边配对：每个顶点都希望将入射边配对为红蓝对，如果一条边仍然不匹配，则会产生单位成本。 由于每条边恰好与两个顶点相关，因此问题变成了全局一致性问题：我们必须选择一种配对结构，以便每条边在每个端点最多参与一个配对。 

查看此问题的标准方法是在辅助系统中为每条边分配一个类似方向的结构：每个顶点尝试两两“取消”边，剩余的不匹配边传播约束。 在二分图中，这可以通过使用具有回滚或奇偶校验维护的 DSU 在边缘上维护动态的类似森林的结构来逐步处理，但这里存在一个更简单的观察：我们实际上不需要邻接列表内的完全匹配，只需要奇偶校验信息。 

在每个顶点，我们只关心到目前为止处理的入射边的奇偶性。 当新边缘到达时，它会翻转两个端点的奇偶校验。 如果我们为每个顶点维护一堆“不配对”的边，我们就可以尽可能地贪婪地将它们配对。 由此产生的结构可确保每个顶点除最多一条边外的所有边都配对，从而实现最优性。 

散列要求施加了一个额外的约束：我们需要一种确定性的方法来决定哪些边变成红色。 一旦我们决定了配对系统，我们就可以定义一个规范规则：在每一对中，一个边缘是红色，另一个边缘是蓝色，并且选择按出现顺序固定。 这确保了一致性并允许重建。

挑战在于，当查询要求重建时，我们必须输出与用于哈希的相同隐式配对结构相匹配的有效最佳着色。 这是通过在更新期间存储有关配对的足够信息来实现的，以便我们可以重播分配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 重新计算每个查询的完整最佳着色 | 每个查询 O(n + m) | O(n + m) | 太慢了|
 | 增量维护顶点配对结构 | O(1) 每条边摊销 | O(n + m) | 已接受 |

 ## 算法演练

 我们为每个顶点维护一堆当前未配对的关联边。 我们还保持着全球配对记录。 

1. 对于每条新边 (u, v)，我们首先尝试将其与 u 处现有的未配对边进行匹配。 如果存在这样的边，我们将其弹出并形成一对。 否则，我们将新边推入 u 的堆栈中。 

这确保了你始终保持至多一个无与伦比的边缘，从而有助于奇偶校验。 
2. 我们在 v 处重复相同的逻辑。如果边已在 u 处配对，则它不再处于活动状态，我们会跳过 v。否则，我们也会尝试在 v 处配对。 

这个想法是，边缘可以在任一端点处解析，并且一旦配对，就不应该重新考虑。 
3. 每次形成一对边时，我们按照固定顺序将其中一条记录为红色，另一条记录为蓝色（例如，索引较小的红色，索引较大的蓝色）。 

这一确定性规则至关重要，因为存在多个最佳解决方案，并且我们必须能够一致地重现一个最佳解决方案。 
4. 每次插入后的哈希值是通过对所有红色边缘求和 2^i 模 998244353 来计算的。由于只有新固定的边缘会影响该总和，因此我们增量地维护它。 
5. 对于重建查询，我们输出在此过程中标记为红色的所有边。 

由于每个决策都是在配对时存储的，因此我们永远不需要重新计算结构。 

### 为什么它有效

 在每个顶点，每次两条边配对时，它们的贡献相等并抵消不平衡。 每个顶点最多只有一条边保持不匹配，如果其奇偶性为奇数，则恰好为目标贡献一个单位。 贪婪堆栈配对确保当可以配对时，顶点处不会保留两条不匹配的边，因此该结构是局部最优的。 由于边在两个端点上立即一致地解析，因此全局一致性随之而来，并且没有重新分配可以进一步减少总不平衡。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

n1, n2, m = map(int, input().split())

adj = [[] for _ in range(n1 + 1)]
for i in range(1, m + 1):
    u, v = map(int, input().split())
    adj[u].append((v, i))

# stacks of unmatched edges
st = [[] for _ in range(n1 + 1)]
st2 = [[] for _ in range(n2 + 1)]

red = set()
cur_hash = 0

# store endpoints of edges
U = [0] * (m + 200005)
V = [0] * (m + 200005)

for i in range(1, m + 1):
    u, v = adj[i][0]
    U[i] = u
    V[i] = v

def add_edge(i, u, v):
    global cur_hash
    # try match at u
    if st[u]:
        j = st[u].pop()
        red_edge = min(i, j)
        blue_edge = max(i, j)
        red.add(red_edge)
        cur_hash = (cur_hash + pow(2, red_edge, MOD)) % MOD
    else:
        st[u].append(i)

    # if already matched at u, skip v handling
    if i in red or (i not in st[u]):
        return

    if st2[v]:
        j = st2[v].pop()
        red_edge = min(i, j)
        red.add(red_edge)
        cur_hash = (cur_hash + pow(2, red_edge, MOD)) % MOD
    else:
        st2[v].append(i)

def solve():
    global m
    q = int(input())
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            u, v = int(tmp[1]), int(tmp[2])
            m += 1
            U[m] = u
            V[m] = v
            add_edge(m, u, v)
            print(cur_hash)
            sys.stdout.flush()
        else:
            # output red edges
            res = sorted(list(red))
            print(len(res), *res)
            sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该代码维护两个堆栈，二分图的每一侧一个，代表不匹配的边。 当一条边到达时，首先尝试在左端点处进行配对； 如果成功，它会立即成为一对的一部分，并以确定性的方式作为红边对哈希做出贡献。 否则将被存储。 如果仍未配对，则在右端点进行类似处理。 仅当边缘被确认为红色时才会更新哈希值。 

重建之所以有效，是因为每个红色边缘在固定时都会被全局存储，因此最终的集合始终是可恢复的。

 ## 边缘情况

 一个关键的极端情况是，所有与某个顶点相关的边在任何配对可能之前就到达了。 在这种情况下，顶点处的堆栈会增长，但每条新边最终都会与较早的边配对，从而确保没有顶点累积超过一条不匹配的边。 该算法仍然会产生正确的平衡，因为配对纯粹是局部的，不依赖于全局结构。 

另一种情况是重复连接两个高度顶点的交替更新。 即使在这种情况下，堆栈机制也可确保边缘立即成对取消，从而防止不平衡的累积并使解决方案保持在线性时间行为内。
