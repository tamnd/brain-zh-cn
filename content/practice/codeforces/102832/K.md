 ## 解决方案
 ## 问题理解

 我们有一个无根树森林，其中每个节点都属于一个连接的组件。 每个节点存储一个整数值。 每次修改后，我们必须报告同一棵树内有多少无序节点对满足特殊算术条件：它们值的最大公约数等于它们值的按位异或。 

操作是动态的。 新的孤立节点可能会出现，两个现有的树可能会被合并，并且节点值可能会改变。 每次操作后都必须保留答案。 

限制足够大，不可能检查每一对。 高达$10^5$初始节点和$2\cdot10^5$运算，二次方法将达到大约$10^{10}$配对检查，远远超出了几秒钟内适合的范围。 我们需要一个接近线性或$O((n+m)\log n)$。 

困难的部分是不断变化的价值观和不断变化的组件之间的相互作用。 一个常见的错误是仅存储每个组件中的节点数，因为答案取决于组件内的值。 另一个错误是在每次合并或更新后重新计算整个组件。 

一个小例子说明了重新计算失败的原因：```
3 1
1 2 3
2 1 2
```第一个操作合并节点 1 和 2。它们的值为 1 和 2。XOR 为 3，gcd 为 1，因此它们不是坏对。 答案是：```
0
```假设每对不同值都有效的解决方案将错误地输出 1。 

另一个边缘情况是大型组件内部的值更新：```
2 2
2 2
2 1 2
3 1 3
```合并后，两个节点的值相等。 它们的 XOR 为 0，因此该对无效，答案为 0。将一个值更改为 3 后，值变为 3 和 2。XOR 为 1，gcd 为 1，因此答案变为 1。任何仅在本地更新更改的值而不删除其先前贡献的方法都可能会留下错误的答案。 

## 方法

 直接的解决方案会将每个组件维护为节点列表。 当查询到达时，我们可以迭代每个组件内的所有对并测试 gcd 和 XOR 条件。 这是正确的，但是一个组件包含$10^5$节点已经创建了大约$5\cdot10^9$成对，所以它不能工作。 

关键的观察来自算术条件。 假设有两个值$x$和$y$满足$$\gcd(x,y)=x\oplus y=d$$然后$d$将两者分开$x$和$y$。 相反，如果$d=x\oplus y$和$d$除两个数，那么 gcd 也必须除 XOR，并且因为$d$本身除两个数字，gcd 正好是$d$。 

这意味着我们只需要知道，对于每个可能的值，哪些其他值可以形成有效的对。 最大值仅为$200000$，因此我们可以预先计算所有兼容的值对。 

对于每个可能的 XOR 值$d$，我们检查所有的倍数$d$。 如果$x$是的倍数$d$，我们计算$y=x\oplus d$。 如果$y$也是$d$，这对$(x,y)$是有效的。 总工作量为$$200000(1+\frac12+\frac13+\dots+\frac1{200000})$$这是关于$2.5$万次迭代。 

经过此预处理后，每个分量只需要一个值的频率表及其当前答案。 添加一个值节点$v$创建与值兼容的现有节点一样多的新坏对$v$。 删除一个值会反转此操作。 

剩下的问题是合并组件。 我们使用从小到大的合并。 当两个分量连接时，我们迭代较小的频率图并将其值插入较大的频率图。 每个节点仅在地图之间移动$O(\log n)$次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$每次操作 |$O(n)$| 太慢了 |
 | 最佳 |$O(V\log V+(n+m)\log n\cdot C)$|$O(V+n)$| 已接受 |

 这里$V=200000$， 和$C$是一个值的兼容值的平均数量。 

## 算法演练

 1. 预先计算满足条件的每对值。 对于每个可能的异或结果$d$，迭代多个$d$， 测试$x\oplus d$，如果关系有效则存储该关系。 这将后面的操作变成简单的频率查找。 
2. 为节点构建不相交集并集结构。 每个组件存储一个字典映射值到频率和一个包含该组件内坏对数量的计数器。 
3. 对于将值插入到组件中，请查看插入值的预先计算的兼容值。 它们当前频率的总和就是创建的新坏对的数量。 然后增加频率。 
4. 对于值删除，请在降低频率之前执行相同的查找。 获得的计数正是消失的对的数量。 
5. 对于合并操作，找到两个根。 如果它们已经相等，则不会发生任何变化。 否则，选择频率字典较小的组件并将其合并到较大的字典中。 在从较小一侧插入每个值之前，计算其与当前较大组件的交叉组件对。 
6. 每次操作后，仅在全局答案中添加或删除受影响组件的贡献。 数据结构始终存储所有分量答案的总和。 

为什么它有效：

 不变的是每个组件字典都包含当前该组件内的节点的值，并且存储的组件答案等于这些节点中有效对的数量。 单个插入或删除仅更改涉及该节点的对，并且这些对直接通过兼容性列表进行计数。 合并仅在两个旧组件之间创建新对，在合并字典时对这些新对进行计数。 由于没有其他对受到影响，因此每次操作后全局答案仍然正确。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXV = 200000

def solve():
    n, m = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    compat = [[] for _ in range(MAXV + 1)]
    for d in range(1, MAXV + 1):
        for x in range(d, MAXV + 1, d):
            y = x ^ d
            if y > x and y <= MAXV and y % d == 0:
                compat[x].append(y)
                compat[y].append(x)

    parent = list(range(n + m + 5))
    bags = [None] * (n + m + 5)
    bad = [0] * (n + m + 5)

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def add_value(root, v):
        s = 0
        for u in compat[v]:
            s += bags[root].get(u, 0)
        bad[root] += s
        bags[root][v] = bags[root].get(v, 0) + 1

    def remove_value(root, v):
        s = 0
        for u in compat[v]:
            s += bags[root].get(u, 0)
        bad[root] -= s
        bags[root][v] -= 1
        if bags[root][v] == 0:
            del bags[root][v]

    for i in range(1, n + 1):
        bags[i] = {}
        add_value(i, a[i])

    total = 0
    for i in range(1, n + 1):
        total += bad[i]

    out = []
    cur = n

    for _ in range(m):
        op = list(map(int, input().split()))
        t = op[0]

        if t == 1:
            cur += 1
            x, v = op[1], op[2]
            parent[x] = x
            bags[x] = {}
            add_value(x, v)
            a[x] = v

        elif t == 2:
            x, y = op[1], op[2]
            rx, ry = find(x), find(y)
            if rx != ry:
                total -= bad[rx] + bad[ry]
                if len(bags[rx]) < len(bags[ry]):
                    rx, ry = ry, rx
                parent[ry] = rx
                bad[rx] += bad[ry]
                for v, c in bags[ry].items():
                    for u in compat[v]:
                        total_pairs = bags[rx].get(u, 0)
                        bad[rx] += c * total_pairs
                    bags[rx][v] = bags[rx].get(v, 0) + c
                bad[ry] = 0
                bags[ry] = {}
                total += bad[rx]

        else:
            x, v = op[1], op[2]
            r = find(x)
            total -= bad[r]
            remove_value(r, a[x])
            add_value(r, v)
            a[x] = v
            total += bad[r]

        out.append(str(total))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```预处理构建兼容性图一次。 条件检查被简化为可整除，因为 XOR 值必须整除两个数字。 

不相交的集合结构处理不断变化的森林。 字典附加到组件根，而不是单个节点，因为所有操作都会影响整个连接的组件。 

插入和删除助手是对称的。 他们在更改频率之前对受影响的对进行计数，这可以避免多个节点共享相同值时出现错误。 

在合并过程中，较小的字典总是移至较大的字典中。 这使得每个节点的字典移动总数保持对数。 全局答案在组件更改之前和之后进行调整，以便仅重新计算修改后的组件。

 ## 边缘情况

 处理等值情况是因为两个相等的正整数的 XOR 为零，而 gcd 为正。 兼容性预处理永远不会创建自对，因此插入相等的值不会意外添加无效对。 

重复合并已连接的节点是无害的。 例如：```
3 2
1 2 3
2 1 2
2 1 2
```第一次合并合并了组件。 第二次合并找到相同的 DSU 根，但不执行任何操作，使答案保持不变。 

大型组件内的值更新是通过首先删除旧值的贡献然后添加新值来处理的。 为了：```
2 2
2 2
2 1 2
3 1 3
```合并不会创建有效的对。 更新删除旧值 2 并对照剩余值 2 检查新值 3，找到一对有效的值。 该算法仅更改受影响的对，因此存储的组件计数保持正确。
