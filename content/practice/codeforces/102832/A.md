 ## 解决方案
 ## 问题理解

 游戏提供七种不同的充值包。 每个套餐都有固定费用，通常提供十倍于优惠券的费用，并且仅在第一次购买特定套餐时提供额外奖励。 套餐可以重复购买，但首次购买后所有购买仅提供普通优惠券。 

凯洛正好有`n`元，必须全部花在充值操作上。 目标是最大化收到的优惠券总数。 答案应该包括每元消费的正常优惠券和首次奖金的最佳选择。 七个套餐的售价分别为`1, 6, 28, 88, 198, 328, 648`，有首次奖金`8, 18, 28, 58, 128, 198, 388`分别。 

重要的观察来自于固定部分和可变部分的分离。 每个礼包的正常奖励中每元正好有十张优惠券，所以无论钱如何分配，正常奖励始终是`10 * n`。 唯一的决定是哪些套餐类型应该至少购买一次才能获得一次性奖金。 

输入限制仅`n <= 2000`。 这对于动态编程来说足够小了。 大约有几百万次操作的解决方案是舒适的，但尝试在七种包类型中每种可能的资金分配将会爆炸，因为组合的数量随着时间的推移而迅速增长。`n`。 

一些边缘情况可能会破坏粗心的实施。 如果`n = 1`，最好的选择是一次性购买一元套餐，赠送`10 + 8 = 18`优惠券。 仅优化奖金而忘记正常奖励的解决方案将输出`8`，这是错误的。 

用于输入`100`，最优答案是`1084`。 88元套餐玩家可购买1次，1元套餐可购买12次。 正常的奖励是`1000`，奖金是`58 + 8`, 给予`1066`，所以这个例子也说明了必须优化分布而不是只取最大的包。 实际的最佳效果来自于更好的组合，给出`1084`。 总是选择最大的负担得起的套餐的贪婪策略会错过这样的组合。 

用于输入`648`，重复购买648元礼包只得到正常奖励加1次奖励。 粗心的实施可能会在每次出现包裹时添加首次奖励，从而产生夸大的答案。 正确的处理方式是每个礼包的奖励最多计算一次。 

## 方法

 直接的暴力解决方案将在七种套餐类型中尝试一切可能的花钱方式。 对于每次分发，它都会计算收到的优惠券并保留最大值。 这是正确的，因为考虑了所有可能的购买计划。 然而，可能的分布数量太大了。 即使只关注最便宜的一元套餐，七种套餐选择中的每一种也已经有很多可能的计数。 枚举所有组合的包类型数量呈指数级增长。 

问题的结构给出了更简单的观点。 由于每元总是贡献十张普通优惠券，因此我们在优化时可以忽略普通优惠券。 我们只需要决定哪些包裹类型会收到第一次购买。 这样的决定只有七个。 

选择第一个奖励包需要花费一定的金钱并提供一定的价值。 选择所有有利可图的首次购买后，剩余的钱可以购买任意套餐，并且每元正好贡献十张优惠券。 剩下的问题是 0/1 背包：七种包裹类型中的每一种都可以选择一次以获得奖励，也可以不选择。 

蛮力之所以有效，是因为它考虑了每个完整的充值计划，但当计划数量变大时就会失败。 观察发现，除了第一次之外，重复购买没有特殊效果，这让我们可以将问题简化为最多选择七个奖励项目。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 | O(7n) | O(7n) | O(n) | 已接受 |

 ## 算法演练

 1.创建一个背包数组，其中`dp[x]`代表准确消费可获得的最大首充奖励`x`首次购买人民币。 最初，每个状态都为零，因为没有收集任何奖金。 
2.将7个充值包分别作为0/1背包物品处理。 对于套餐成本计算`cost`元与给予`bonus`优惠券，将各州从较大金额更新为较小金额。 过渡是跳过此包或购买一次。 
3. 处理完所有包裹后，在所有金额中找到最佳奖金价值，最多可达`n`。 首次购买的金额不需要准确无误`n`，因为剩下的钱还是可以正常花的。 
4. 添加`10 * n`最好的奖金。 这是最终的答案，因为无论充值计划如何，每一元都贡献相同的正常奖励。 

之所以需要向后更新，是因为每个礼包只能给予第一次奖励一次。 从低到高的更新将允许在同一迭代中多次选择相同的包。 

为什么有效：动态编程状态完全考虑了影响奖金的唯一选择。 每个包要么贡献一次第一个奖励，要么什么也不贡献。 处理完所有包后，首次购买的每个有效子集都已被考虑。 剩余的钱不影响奖金选择，并且始终贡献相同的正常奖励，因此添加`10 * n`完成最优总数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    costs = [1, 6, 28, 88, 198, 328, 648]
    bonuses = [8, 18, 28, 58, 128, 198, 388]

    dp = [0] * (n + 1)

    for cost, bonus in zip(costs, bonuses):
        for money in range(n, cost - 1, -1):
            dp[money] = max(dp[money], dp[money - cost] + bonus)

    print(n * 10 + max(dp))

if __name__ == "__main__":
    solve()
```数组`costs`和`bonuses`存储七个可能的首次购买。 每对构成一个背包物品。 

嵌套循环执行 0/1 背包转换。 循环结束`money`来自`n`向下，因为当前包不得重用在同一迭代中较早创建的状态。 如果价格上涨，购买一个包裹可能会意外地导致多次购买同一个包裹。 

决赛`max(dp)`被用来代替`dp[n]`因为第一次购买可能不会花掉所有的钱。 例如，Kelo可能花198元购买一个套餐，获得大笔奖金，然后有剩余的钱，最好按普通充值处理。 

所有值都保持较小。 正常奖励上限仅为`20000`优惠券，而且奖金总额也很小，所以Python整数溢出不是问题。

 ## 边缘情况

 对于`n = 1`，算法处理一元包并更新`dp[1]`到`8`。 最终的答案是`10 + 8 = 18`。 它从不尝试购买更昂贵的套餐，因为这些转变是不可能的。 

为了`n = 648`，动态规划阶段可选择648元套餐，仅获得一次性奖励`388`。 剩下的计算加上`6480`普通优惠券，赠送`6868`。 重复购买同一包不会被表示，因为每个包仅处理一次。 

对于不等于任何套餐价格的预算，例如`n = 100`，该算法在奖金选择期间不需要精确填充。 它会找到首笔购买金额最多为100元的最佳子集，然后通过固定金额自动将未使用的金额转换为普通优惠券。`10 * n`学期。 这可以防止因强制进行人为的精确背包匹配而损失价值。
