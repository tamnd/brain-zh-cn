 ## 解决方案
 ## 问题理解

 我们需要创建一个数组`n`表示每行中黑色单元格数量的非负整数。 黑色单元格的总数必须恰好是`s`。 在每两相邻行之间，黑色单元的数量可以恰好增加 1 或恰好减少`k`。 

输入给出行数、允许的减少值以及所需的黑色单元格总数。 输出是任何有效的行值序列，或者`-1`如果不存在这样的序列。 

极限`n <= 100000`意味着解必须接近线性。 尝试多种可能的数组、对总和进行动态规划或任何取决于`s`直接是不可能的，因为`s`可以达到`10^18`。 

棘手的情况是由于将每个元素增加相同的数量而改变总和的倍数的事实引起的`n`，而不是任意值。 仅使用的构造`+1`在以下情况下转换失败：```
n = 3, k = 2, s = 15
```仅使用增加的总和等于`0`模数`3`，但有效的答案例如`6 4 5`需要减少过渡。 

另一种失败情况是答案仅在使用多次减少后才存在。 例如：```
n = 5, k = 10, s = 1
```从较大的正值开始然后向下调整的简单方法可能会违反非负性，因为`10`可以快速创建负行。 

最后的边缘情况是当模块化条件不可能时。 例如：```
n = 4, k = 3, s = 2
```这里每个转换都会通过以下任一方式更改行值`1`或者`-3`，所以所有行都有固定的模关系`4`。 如果所需的总和与该关系不匹配，则任何移位都无法修复它。 

## 方法

 一个蛮力的想法是独立决定每个转换。 有`n-1`过渡，每个人都有两种选择，所以这探讨了`2^(n-1)`的可能性。 它是正确的，因为它检查了数组的每种可能的形状，但是对于`n = 100000`这是完全不可行的。 

有用的观察来自于描述与全部增加情况相关的每个转变。 设第一行为`A`。 如果每个转变都是`+1`，行的值`i`会是`A + i - 1`。 相反，减少过渡会减去额外的`k+1`与此相比。 

如果头寸之间发生减少`i`和`i+1`，它会影响后面的每一行。 它对总和的贡献恰好是`k+1`次`(n-i)`。 因此，如果我们让`D`是所选权重的总和`1,2,...,n-1`，总和变为：```
s = n*A + n(n-1)/2 - (k+1)*D
```可能的值`D`每个数字都来自`0`到`n(n-1)/2`，因为该范围内的任何数字都可以表示为`1,2,...,n-1`。 

问题简化为找到一个有效的`D`满意：```
(k+1)*D = n(n-1)/2 - s (mod n)
```这是线性同余。 找到合适的后`D`，第一个值`A`已确定。 我们选择最大可能的有效值`D`在它的同余类中，这样`A`保证为非负数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 让`C = n(n-1)/2`。 全增加序列贡献`C`到总和，因此剩余部分由第一个值和减操作控制。 
2. 求解同余：```
(k+1)D ≡ C-s (mod n)
```使用最大公约数。 如果右边不能被整除`gcd(k+1,n)`，不存在解。 
3. 计算一个解决方案`D0`模数`n/gcd(k+1,n)`使用模逆`(k+1)/gcd(k+1,n)`。 
4. 移至最大值`D`不超过`C`具有相同的残基`D0`。 此选择最大化减法项并防止计算的第一个值变为负值。 
5. 计算：```
A = (s-C+(k+1)D)/n
```然后`A`是第一行值。 
6. 代表`D`作为一个子集`1,2,...,n-1`。 从最大权重向下迭代。 如果当前体重符合`D`，在那里放置一个减少过渡。 
7. 从以下开始构建数组`A`。 对于每个转换，添加`1`通常或减去`k`当选择减少过渡时。 

该结构背后的不变性是，每个选定的减少都准确地贡献了其指定的权重`D`。 同余保证总和正确，并选择最大的有效值`D`保证初始偏移量足够大。 由于序列是直接从有效转换构建的，因此每个相邻对都满足所需的规则。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def egcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x, y = egcd(b, a % b)
    return g, y, x - (a // b) * y

def solve_case(n, k, s):
    if n == 1:
        return "0" if s != 0 else "0"

    c = n * (n - 1) // 2
    g, _, _ = egcd(k + 1, n)

    if (c - s) % g != 0:
        return "-1"

    mod = n // g
    if mod == 1:
        d0 = 0
    else:
        a = (k + 1) // g
        b = (c - s) // g
        _, x, _ = egcd(a, mod)
        d0 = (b * (x % mod)) % mod

    d = c - ((c - d0) % mod)
    a0 = (s - c + (k + 1) * d) // n

    cuts = [False] * n
    rem = d
    for i in range(n - 1, 0, -1):
        if rem >= i:
            rem -= i
            cuts[i] = True

    ans = [a0]
    for i in range(1, n):
        if cuts[i]:
            ans.append(ans[-1] - k)
        else:
            ans.append(ans[-1] + 1)

    return " ".join(map(str, ans))

def main():
    n, k, s = map(int, input().split())
    print(solve_case(n, k, s))

if __name__ == "__main__":
    main()
```代码首先处理模方程。 扩展欧几里得算法提供了同余所需的逆，而不依赖于库函数。 

价值`d`选择作为其残留类别的最大有效代表。 这是避免负起始值的细节。 较小的有效值可以满足数学要求，但仍然需要负的第一行。 

这`cuts`数组存储哪些转换是减少的。 贪心子集构造之所以有效，是因为权重恰好是`1`通过`n-1`，因此首先取最大的可用权重总是留下可表示的余数。 

Python 整数不会溢出，这是必要的，因为中间产品如`(k+1)*d`可以超出 64 位有符号限制。

 ## 边缘情况

 对于`n = 1`，没有需要满足的转换。 该实现单独处理这个问题，因为模块化结构假设至少存在一个转换。 

对于不可能的同余，例如：```
4 3 2
```我们有`gcd(4,4)=4`， 但`C-s = 4`，所以这个特定的例子实际上是可以解决的。 真正不可能的情况是：```
4 3 3
```在哪里`C-s = 3`不能被整除`4`。 该算法在尝试构建之前会拒绝它。 

对于非常小的金额，所选择的`D`必须足够大。 该算法取最大的有效值`D`，增加减少的贡献并减少所需的第一个值。 这可以防止出现数学上有效但为负的数组。 

对于较大的值`s`，相同的结构仍然有效，因为第一个值吸收了额外的量。 将所有行增加相同的数量会保留每个转换条件，并且仅将总数更改为`n`。
