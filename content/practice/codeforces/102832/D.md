 ## 解决方案
 # 问题理解

 该序列由涉及按位 AND 的递归定义。 位置项`n`通过查看所有较早的头寸获得，这些头寸的索引是通过清除至少一组位而形成的`n`，取这些项中的最大值，并将其乘以`c`。 任务是计算索引中所有项的总和`0`通过给定的索引`n`, 取模`10^9+7`。 原始问题陈述和约束来自 Codeforces Gym 102832D。 

输入索引`n`不以普通十进制整数形式给出。 它以二进制字符串形式提供，最多可包含 3000 位。 这立即排除了任何依赖于迭代每个值的事情`0`到`n`， 因为`n`其本身可能是天文数字般巨大。 一个3000位二进制数的数字大约是`2^3000`，因此即使算法对每个值进行一次操作也是不可能的。 解决方案必须取决于位数`n`，不在数字大小上`n`。 

参数`c`可以大到`10^9`，但所有计算均以模进行`10^9+7`。 这意味着我们只需要模乘和求幂，并且不需要存储实际的序列值。 

第一个挑战是了解复发真正产生的结果。 直接实现将尝试保留所有先前的值，但索引范围使该方法无法使用。 有用的边缘情况是那些揭示隐藏模式的情况。 

用于输入`0 5`，唯一的术语是`a_0 = 1`，所以答案是`1`。 将二进制字符串视为普通整数并尝试从第一个设置位开始位 DP 的解决方案可能会意外错过零情况。 

用于输入`1 0`，条款是`a_0 = 1`和`a_1 = 0`，所以答案是`1`。 一个不小心使用的公式`0^0`或者假设每一项都是由`c`不分隔索引零可能会产生不正确的结果。 

用于输入`10 2`，指数是`0, 1, 2`，它们的值为`1, 2, 2`，所以答案是`5`。 一个常见的错误是只处理设置的位`n`并忘记二进制分解中出现的所有较小数字的贡献。 

# 方法

 强力解决方案将一次生成一项序列。 对于每个索引`x`，它会检查每个较小的索引`i`, 计算`x & i`，并使用已计算的最大值。 这是正确的，因为它直接遵循递归。 然而，它需要处理最多`n`条款，以及`n`可能接近`2^{3000}`。 即使忽略对最大值的内部搜索，简单地访问每个索引也是不可能的。 

改变问题的第一个观察结果是`n & i`始终是子掩码`n`。 每个索引均可到达`n`AND 运算只是一个版本`n`删除了一些设置位。 如果`n`有`k`设置位，最佳先前值来自于保留尽可能多的设置位，同时删除至少其中之一。 这给出了关系：`a_n = c^(number of set bits in n)`。 

基本情况也适合，因为`a_0 = 1 = c^0`。 

现在的任务不再是关于奇怪的重复。 我们只需要：`sum(c^popcount(i))`对于每个二进制数`i`从`0`到`n`。 

剩下的挑战是在不枚举数字的情况下计算这个总和。 我们处理的位`n`从最重要的方面来看。 当一点点`n`是`1`，当前位设置为的所有数字`0`并且任意剩余的低位小于`n`。 他们的贡献可以算作一个完整的区块。 如果有`k`剩余的空闲位置，该块包含这些位的所有可能选择，因此其总贡献遵循简单的递归。 

让`f(k)`是`c^popcount(x)`全面的`k`- 位数字。 每个位要么是`0`或者`1`。 选择`0`保持贡献不变，同时选择`1`将其乘以`c`， 所以：`f(k) = f(k-1) * (1 + c)`和`f(0) = 1`。 

扫描时`n`，我们维持多少`1`位已经出现了。 每当我们遇到一个`1`，我们添加与所有先前位匹配的数字的贡献，将`0`在这里，并使用任何剩余的位。 这些数字具有来自先前设置位的固定贡献乘数和来自剩余位置的完整后缀贡献。 

这两种方法的区别如下：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(n) | 太慢了 |
 | 最佳 | O( | n | ) |

 # 算法演练

 1. 读取二进制表示`n`和价值`c`。 预先计算每个可能的后缀长度的贡献。 对于后缀`k`位，存储总和`c^popcount`超过这些位可以形成的所有数字。 复发率是`dp[k] = dp[k-1] * (1+c)`。 
2、办理案件`n = 0`分别地。 只有一个术语`a_0`，其值为`1`。 
3. 扫描位`n`从左到右。 保持`ones`，已处理的设置位数，以及`ans`，所有较小前缀的累积答案。 
4. 当当前位为`0`，继续扫描。 每个具有此前缀的有效号码还必须具有`0`这里。 
5. 当当前位为`1`，计算所有使用的数字`0`在这个位置。 它们已经小于`n`，它们的剩余位可以是任何东西。 贡献是选择先前设置位的方式数量乘以预先计算的后缀和。 
6. 添加该块后，包括`n`通过将其当前位视为`1`，这增加了迄今为止看到的设置位的数量。 
7. 处理完所有位后，添加`n`本身并输出结果模`10^9+7`。 

为什么它有效：循环创建一个值仅取决于索引中设置的位数。 二进制扫描将所有数字从`0`到`n`根据它们变得小于的第一个位置分成不相交的组`n`。 每个数字恰好出现在一个这样的组中，并且每个组的贡献是根据剩余位的独立选择来计算的。 之前维护的计数`1`位正确地考虑了固定前缀贡献，因此最终的总和恰好包含每个所需项一次。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve():
    n, c = input().split()
    c = int(c) % MOD

    if n == "0":
        print(1)
        return

    m = len(n)

    suf = [1] * (m + 1)
    mul = (1 + c) % MOD
    for i in range(1, m + 1):
        suf[i] = suf[i - 1] * mul % MOD

    ans = 0
    ones = 0

    for idx, ch in enumerate(n):
        if ch == '1':
            rem = m - idx - 1
            ans += pow(c, ones, MOD) * suf[rem] % MOD
            ans %= MOD
            ones += 1

    ans += pow(c, ones, MOD)
    ans %= MOD

    print(ans)

if __name__ == "__main__":
    solve()
```预计算数组`suf`存储所有后缀的完整贡献。 如果后缀多了一位，则每种旧的可能性都会出现两次：一次该位等于 0，一次等于 1。 第二个副本获得的系数为`c`，这给出了乘数`1 + c`。 

主循环实现了上述的二进制分解。 变量`ones`表示已经固定的前缀中设置的位数。 当当前位为`1`，将其更改为`0`使得数字更小，并且较低位变得不受限制。 期限`pow(c, ones, MOD)`处理固定前缀，而`suf[rem]`处理自由后缀。 

最后的加法是必要的，因为扫描只计算在某些位变小的数字。 原来的号码`n`直到最后才包含其本身。 

Python整数不会溢出，但所有乘积都会减少模数`10^9+7`保持值较小。 二进制长度可以是3000，所以使用模幂也是安全的。

 # 边缘情况

 对于`0 5`，算法立即返回`1`。 这避免了将空位集视为正常转换并正确保留了特殊定义`a_0`。 

为了`1 0`，公式给出`a_0 = 1`和`a_1 = 0^1 = 0`。 在扫描过程中，较小的块贡献`1`，最后一项贡献`0`，给出正确答案`1`。 

为了`10 2`，扫描看到第一个位设置。 它计算该位被清除的数字，即`0`和`1`, 给予`1 + 2 = 3`。 最终值`a_2 = 2`然后添加。 该分区恰好覆盖每个索引一次，产生`5`。 

对于非常大的二进制字符串，例如由 3000 个组成的二进制字符串，该算法从不尝试生成序列。 它每位只执行固定量的工作，因此相同的方法仍然适用。
