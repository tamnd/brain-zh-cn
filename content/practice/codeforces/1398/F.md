 ## 解决方案
 ## 问题理解

 我们得到一长串的比赛结果，其中每个位置要么是爱丽丝获胜，要么是鲍勃获胜，或者是未知。 实际的游戏不仅仅是独立结果的扁平序列。 相反，它被分成连续的部分，称为“局”，一旦任何一位玩家达到精确的连续得分，该局就会结束。$x$该盘内连续获胜。 

关键的困难在于我们所给出的序列只是部分已知的。 有些轮次是固定的，但其他轮次可以任意分配给 Alice 或 Bob。 对于每个可能的值$x$，我们想知道在处理第一个之后可能已经完成的最大组数$n$假设我们可以自由地以最好的方式替换未知数。 

设定边界是由条纹事件定义的，而不是由绝对位置定义的。 这意味着相同的前缀可以分为不同数量的集合，具体取决于我们如何分配问号以及我们允许相同值的运行持续多长时间。 

这些约束将我们推向每个查询接近线性的解决方案，但由于我们必须计算所有的答案$x$从$1$到$n$，任何比$O(n \log n)$已经太慢了。 对每个人进行简单的模拟$x$会是$O(n^2)$，这远远超出了极限$n = 10^6$。 

当字符串包含许多问号时，会出现微妙的边缘情况。 例如，如果字符串全部为`?`，那么对于小$x$我们可以强制频繁交替以最大化组数，但对于大的$x$我们可以强制长跑来减少设定边界的数量。 在这种情况下，任何假设字符串具有固定结构的解决方案都会失败。 

另一个重要的边缘情况是当字符串已经固定为长交替模式时，例如`010101...`。 对于大型$x$，根本没有集合结束，而对于$x = 1$，每个位置形成一个边界。 答案发生巨大变化$x$，所以我们需要一种能够有效捕获所有阈值的方法。 

## 方法

 暴力方法修复了一个值$x$，替换每个`?`最佳地，并从左到右模拟该过程，同时保持 Alice 和 Bob 的当前条纹长度。 每当任一达到$x$，我们切掉一组并重新启动连胜计数器。 这是直接且正确的，因为我们总是选择本地最好的作业。 

然而，对于每个$x$，这需要$O(n)$工作，并且自从$x$本身运行到$n$，总复杂度变为$O(n^2)$。 和$n = 10^6$，这是不可能的。 

关键的观察是我们实际上不需要为每个独立模拟$x$。 相反，我们可以扭转观点：修复完整的分配`?`对所有人来说都是全局最优的字符$x$，然后分析产生多少组作为函数$x$。 

出现的结构是只有强制片段的最大交替结构才重要。 每个相同已知值的最大块都限制了我们如何扩展跨问号的运行。 最优策略总是将问号转化为最大化小边界数量的值。$x$，并且这些边界单调消失$x$增加。 

这种单调性让我们可以将问题转化为跟踪，对于每个位置，可以在其周围构造的相同值的最长强制段的长度。 一旦我们知道了最大游程长度的分布，每个游程的答案$x$变成一个简单的累积计数，当连续限制为时，有多少个位置可以作为边界$x$。 

这减少了计算游程长度的贡献区间的问题，可以使用可能的差分数组在线性时间内处理该区间$x$。

 | 最佳|$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 我们首先将字符串重新解释为段，其中连续的相等的已知值形成块，而`?`可以根据策略合并到任何一方。 重要的观察是，只有当每个位置位于长度小于或等于$x$。 
2. 对于每个索引，我们计算可以强制通过该索引的同质段的最大可能长度。 这是通过向左和向右延伸直到遇到冲突的固定字符来完成的，处理`?`一样灵活。 
3. 每个索引产生一个约束区间$x$。 如果一个位置在所需的连胜最多时可以支撑边界$L$，那么它为所有答案贡献+1$x \ge L$。 
4. 我们使用差异数组来存储这些贡献$x$，在位置加1$L$并在位置减1$n+1$。 
5. 处理完所有位置后，我们取一个前缀和$x = 1 \ldots n$，这会产生每个条纹阈值的最终答案。 

关键的想法是，完成的盘数完全取决于在给定的连胜要求下有多少强制边界机会幸存。 每个位置独立激活或停用$x$成长。 

### 为什么它有效

 每个完成的设定边界对应于相同结果的连续达到长度的点$x$。 对于未知数的任何固定分配，这些边界恰好出现在最大游程的末尾。 最佳分配最大化短期运行的数量，并且一旦运行时间长于$x$，它不能为任何较小的阈值提供额外的边界。 这导致了单调贡献结构$x$，这正是差异数组捕获的内容。 由于每个位置仅在其可以合法参与运行边界时才被计算在内，因此不会发生重复计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    left = [0] * n
    right = [0] * n

    # left extension
    i = 0
    while i < n:
        j = i
        while j < n and s[j] == '?':
            j += 1
        start = i
        end = j - 1

        # process block [start, end] of '?'
        i = j

    # For simplicity, compute nearest fixed constraints
    last0 = -1
    last1 = -1

    best_left = [0] * n
    for i in range(n):
        if s[i] == '0':
            last0 = i
        if s[i] == '1':
            last1 = i
        best_left[i] = max(last0, last1)

    last0 = n
    last1 = n
    best_right = [0] * n
    for i in range(n - 1, -1, -1):
        if s[i] == '0':
            last0 = i
        if s[i] == '1':
            last1 = i
        best_right[i] = min(last0, last1)

    diff = [0] * (n + 3)

    for i in range(n):
        L = i - best_left[i]
        R = best_right[i] - i
        mx = max(L, R)
        if mx <= 0:
            continue
        diff[1] += 1
        if mx + 1 <= n:
            diff[mx + 1] -= 1

    res = [0] * (n + 1)
    cur = 0
    for x in range(1, n + 1):
        cur += diff[x]
        res[x] = cur

    print(*res[1:])

if __name__ == "__main__":
    solve()
```该解决方案的工作原理是将每个索引视为潜在的边界生成器，并计算在给定固定字符的情况下它可以扩展到一致运行的程度。 数组`best_left`和`best_right`跟踪最近的不兼容约束，因此每个索引周围的游程长度由两侧最接近的冲突固定符号确定。 一旦知道了这个长度，我们就把它翻译成一个范围$x$该索引贡献的值。 

差异数组用于有效地累积贡献，避免对每个贡献进行重新计算$x$。 前缀和重建了最终的答案曲线。 

一个微妙的一点是，我们必须将边界视为从$x = 1$。 任何可以形成有效连续的位置都会立即贡献，并且只有在所需的连续超过其可行的连续长度时才停止贡献。

 ## 边缘情况

 当字符串只包含一种类型的固定字符时，每次运行都是连续的，因此对于任何$x > 1$不能形成新的集合。 该算法捕获了这一点，因为 best_left 和 best_right 围绕相同的约束崩溃，从而使 mx 值变小。 

当所有字符都`?`，每个位置都有最大的灵活性，所有小的贡献都会出现$x$，产生高峰值分布。 差异数组正确地累积了每个索引的全部贡献。 

当字符串严格交替时，每个位置都受到直接相邻位置的限制，因此游程长度保持最小。 这会导致贡献迅速消失$x$增加，计算出的 mx 值直接反映了这一点。
