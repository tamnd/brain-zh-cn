[CF 1398B - 子字符串删除游戏](https://codeforces.com/problemset/problem/1398/B)

 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 该游戏在二进制字符串上运行，可以将其视为相同字符的相邻块的序列。 在每一回合中，玩家移除由相同字符组成的连续片段，并将字符串的剩余两个部分缝合在一起。 分数不在于玩家走了多少步，而在于具体走了多少步`1`他们在整个过程中亲自删除了字符。 

关键的微妙之处在于，移动并不限于删除单个角色。 玩家可以在一次操作中删除一整串相同的角色，这意味着游戏从根本上讲是选择要消除哪些块以及以什么顺序消除，而剩余的运行的结构随着块合并而不断变化。 

每个测试用例的输入大小都很小，字符串长度最多 100 个，最多 500 个测试用例。 这立即排除了游戏状态的任何指数模拟。 即使每个测试用例对所有子串进行三次或二次模拟也是可以接受的，但任何探索完整博弈树的行为都是不必要的矫枉过正。 

如果将其视为“计算爱丽丝可以在交替的块中抓取的数量”，就会出现一个幼稚的错误。 但这会失败，因为删除可以合并字符串的分离部分，从而创建新的邻接和新的机会。 

例如，考虑`101`。 如果爱丽丝贪婪地删除第一个`1`，字符串变为`01`，但是如果她去掉中间的`0`，字符串变为`11`，极大地改变了未来的得分机会。 即使对于如此微小的投入，忽视结构性变化的战略也会出现错误计算。 

另一个失败案例是交替字符串，例如`101010`。 最佳发挥取决于移除后的分组效果，并且天真贪婪地移除可见块并不能保留最佳结构。 

## 方法

 蛮力视角是将整个游戏模拟为极小极大搜索。 每个状态都是一个字符串，每次移动都会选择一系列相同的字符来删除。 从一个状态可能移动的次数与运行次数成正比，每次移动后字符串都会发生变化，产生一个新的状态。 这很快就会变成一个完整的博弈树。 

尽管字符串长度最多为 100，但每次移动的分支因子大约为 O(n)，深度也是 O(n)，导致状态数量达到天文数字。 记忆化原则上有帮助，但不同状态的数量仍然是指数级的，因为删除可以以多种方式重新排序邻接和合并运行。 

关键的观察结果是，单个角色的身份并不像连续游戏的结构那么重要。 一旦我们将字符串压缩成块，游戏就变成了有多少个`1`-方块的存在以及它们如何与周围环境相互作用`0`- 块。 每次移动都会删除整个区块，唯一重要的是爱丽丝或鲍勃是否能够采取行动`1`-阻止它变得不可访问或合并到不太有利的配置中。 

一个更简单、更深入的观点是，所有`1`区块最终会被某人删除，玩家轮流拿走整个区块。 由于每次移动恰好删除一个连续的块，因此在压缩效果稳定后，游戏减少为按其位置的降序选择块，并且最佳游戏与按排序顺序处理块长度一致。 

一旦字符串被压缩为运行，该过程实际上就变成了基于回合的段权重选择，其中每个`1`-run 将其长度贡献给获得它的玩家，并且两个玩家以贪婪的方式交替从最大的可用贡献中挑选。 

这减少了从动态字符串操作到游程长度上的静态多集游戏的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（游戏树）| 指数| 指数| 太慢了 |
 | 运行压缩+贪婪选择| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 首先将字符串压缩成最大连续段。 每个段被记录为由其字符和长度组成的对。 这是必要的，因为每次移动都会删除整个连续的相等块，因此游戏的自然原子单位是运行，而不是角色。 
2. 仅提取包含以下内容的段的长度`1`。 这些代表了爱丽丝得分的所有可能来源，因为只删除了`1`为她的分数做出贡献。 
3. 对这些进行排序`1`- 段长度按降序排列。 原因是两名球员都在有效地竞争尽早获得大块得分，因为延迟大块只会让对手处于同等或更有利的位置。 
4. 模拟交替翻转此排序列表。 Alice 取第一个、第三个、第五个等等最大的可用值`1`- 段，而鲍勃则选择第二个、第四个等。 
5. 将 Alice 所取的值相加，得出最终答案。 

关键的推理步骤是，一旦字符串被简化为独立的块，远处块之间的相互作用就不再改变它们的贡献大小。 游戏的复杂性分解为一个简单的独立权重竞争分配问题。 

### 为什么它有效

 每一步都会删除一个最大的连续块。 完全压缩后，唯一有意义的决定是先删除哪些块。 由于合并永远不会增加总数量`1`s 在一个块中，每个`1`- 节段保持其重量直至被移除。 交替轮流顺序按降序固定这些权重的所有权，并且任何移动的重新安排都不能改善爱丽丝对较小区块的访问，而不会让鲍勃更早地访问相等或更大的区块。 这将最优策略锁定为对排序段权重的贪婪选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        s = input().strip()
        
        ones = []
        
        i = 0
        n = len(s)
        
        while i < n:
            j = i
            while j < n and s[j] == s[i]:
                j += 1
            
            if s[i] == '1':
                ones.append(j - i)
            
            i = j
        
        ones.sort(reverse=True)
        
        ans = 0
        for k in range(0, len(ones), 2):
            ans += ones[k]
        
        print(ans)

if __name__ == "__main__":
    solve()
```实现首先扫描字符串并构建游程长度。 内部循环识别最大连续段，确保每个块都被原子地处理。 仅存储 1 的片段，因为零片段对 Alice 的分数没有贡献。 

按降序对这些段长度进行排序与​​之前导出的贪婪分配策略一致。 从索引零开始对每个第二个元素求和的循环直接对应于 Alice 获取第一个、第三个和后续的最佳可用块。 

一个常见的实现陷阱是忘记压缩运行，而是计算单个字符，这打破了移动在整个块上运行的假设。 

## 工作示例

 考虑输入`01111001`。 压缩步骤产生片段`0 | 1111 | 00 | 1`。 这`1`- 段有长度`[4, 1]`。 

| 步骤| 分段 | 已排序 | 爱丽丝精选| 运行总计 |
 | ---| ---| ---| ---| ---|
 | 开始| [4, 1] | [4, 1] | 4 | 4 |
 | 下一页 | [4, 1] | [4, 1] | 1（鲍勃取 1）| 4 |

 爱丽丝的分数变为 4。 

现在考虑`101010`。 压缩给出`1 | 0 | 1 | 0 | 1 | 0`，所以这些段是`[1, 1, 1]`。 

| 步骤| 分段 | 已排序 | 爱丽丝精选| 运行总计 |
 | ---| ---| ---| ---| ---|
 | 开始| [1, 1, 1] | [1, 1, 1] | 1 | 1 |
 | 下一页 | [1, 1, 1] | [1, 1, 1] | 1 | 2 |
 | 下一页 | [1, 1, 1] | [1, 1, 1] | 1 | 3 |

 这表明在完全交替的结构中，爱丽丝仍然收集可用总数的半舍入`1`-块权重，与贪婪交替一致。

def run(inp: str) -> str:

 ## 边缘情况

 完全零的字符串，例如`0000`不产生`1`段，因此算法正确地返回零，因为得分块列表为空并且爱丽丝永远不会获得分数。 

完全像一根弦`111111`压缩成长度为六的单段。 爱丽丝在第一次移动时立即获取它，并且由于没有其他段，她会不受干扰地接收整个值。 

交替结构如`1010101`产生多个单元段。 排序保留了它们的独立性，而交替选择可确保 Alice 一致地捕获所有其他片段，而无需模拟字符串中的结构变化。
