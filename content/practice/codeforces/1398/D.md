 ## 问题理解

 我们得到了三组棍子，按颜色分组。 每个颜色组包含多个棒对，每对都有一个长度值。 通过选择两种不同的颜色并将每种颜色中的一对棍子配对成为矩形的相邻边来形成矩形。 这种矩形的贡献是两个选定长度的乘积。 

每对棍棒最多只能使用一次，我们可以忽略任何未使用的棍棒对。 任务是选择不相交的颜色对并将它们配对成矩形，以使所有产生的产品的总和最大化。 

重新表述该过程的一个有用方法是，每个操作都消耗来自不同数组的两个数字并获得它们的乘积。 目标是在每个数字最多只能使用一次的约束下最大化此类成对乘积的总和。 

约束很小：每个数组最多有 200 个元素，因此总共最多有 600 个值。 这允许对涉及我们从每个排序数组中获取多少元素的状态进行动态编程。 200 的任何三次方都可以接受，但 600 的任何指数则不可接受。 

当一种颜色比其他颜色大得多时，就会出现微妙的边缘情况。 像贪婪地配对全局最大剩余元素这样的幼稚策略可能会失败，因为它可能会消耗低产量配对中的大量元素，从而阻止其在以后的更高产量配对中使用。 例如，如果红色包含 100、90，而绿色/蓝色包含多个中等值，则与将其保存为较大的蓝色值相比，尽早将 100 与较小的绿色值配对可能会减少总数。 

当最佳全局配对在每个步骤中不是局部最优时，就会出现另一种失败情况。 由于每个选择仅从两个数组中删除元素，因此决策结构在步骤之间并不独立，因此贪婪选择是不够的。 

## 方法

 暴力方法将尝试模拟在三个阵列中挑选对的所有可能方法。 在每一步中，我们选择任意两种剩余颜色，从每种颜色中选择一个元素，然后递归。 多达 600 个元素，这形成了一个巨大的分支过程。 即使我们减少对称性，匹配的数量也会组合增长，从而有效地探索三方多重集中的匹配。 这远远超出了可行的限度。 

关键的观察结果是，按降序对每个数组进行排序可以尽早对齐大值，并且最佳解决方案将仅使用这些排序数组的前缀。 这是因为，如果使用较小的元素，而相同颜色的较大元素未使用，则交换它们只能增加或保留总数。 

一旦我们承认我们只关心前缀，结构就变得易于管理。 我们通过从每种颜色中获取多少元素来定义状态。 在任何状态下，最后一次操作必须将三种颜色中的两种配对。 这自然会导致 3D 动态编程解决方案，其中转换表示在两种颜色之间选择一对并推进它们的前缀指针。 

每次转换都会将两个选定数组中下一个未使用的元素相乘，并将该乘积添加到先前状态的最佳已知值。

 | 暴力匹配| 指数| 指数| 太慢了 |
 | 排序前缀上的 3D DP | O(RGB) | O(RGB) | 已接受 |

 ## 算法演练

 我们按降序对所有三个数组进行排序，以便获取较早的元素始终意味着首先获取较大的贡献。 

我们定义一个动态规划表`dp[i][j][k]`，表示使用第一个后​​可实现的最大总面积`i`红色元素，`j`绿色元素，以及`k`蓝色元素。 

1. 将所有状态初始化为负无穷大，除了`dp[0][0][0] = 0`。 这表示没有形成矩形的空选择。 
2.来自任何州`(i, j, k)`，我们可以通过配对形成一个新的矩形：

 - 一根红色和绿色的棍子，如果`i < R`和`j < G`- 一根红色和蓝色的棍子，如果`i < R`和`k < B`- 一根绿色和蓝色的棍子，如果`j < G`和`k < B`每个过渡都使用每个选定颜色中的下一个未使用的元素。 
3. 对于每个有效的转换，我们通过添加两个选定的棒长度的乘积来更新下一个状态。 例如，从`(i, j, k)`到`(i+1, j+1, k)`我们添加`r[i] * g[j]`。 
4. 我们按升序迭代所有状态`(i + j + k)`以便在需要之前计算所有先决条件。 
5. 最终答案是所有状态的最大值，因为我们可能随时停止配对。 

重要的推理步骤是，一旦数组按降序排序，任何最佳解决方案都不会从跳过较大的可用元素而选择相同颜色的较小元素中受益。 这确保了前缀属性并验证了 DP 状态定义。 

### 为什么它有效

 在任何时候，如果解决方案使用较小的元素，而相同颜色中存在较大的未使用元素，则交换它们会增加或保留该矩形的贡献，而不会影响可行性。 重复此参数会将所有选定的元素推为前缀。 因此，每个最优解对应于 DP 状态空间中的某个路径，并且每个 DP 转换对应于一​​个有效的矩形选择。 这创建了对所有最佳配置的完整且不重叠的探索。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    R, G, B = map(int, input().split())
    r = sorted(map(int, input().split()), reverse=True)
    g = sorted(map(int, input().split()), reverse=True)
    b = sorted(map(int, input().split()), reverse=True)

    dp = [[[0] * (B + 1) for _ in range(G + 1)] for _ in range(R + 1)]

    ans = 0

    for i in range(R + 1):
        for j in range(G + 1):
            for k in range(B + 1):
                cur = dp[i][j][k]
                ans = max(ans, cur)

                if i < R and j < G:
                    dp[i + 1][j + 1][k] = max(dp[i + 1][j + 1][k],
                                               cur + r[i] * g[j])
                if i < R and k < B:
                    dp[i + 1][j][k + 1] = max(dp[i + 1][j][k + 1],
                                               cur + r[i] * b[k])
                if j < G and k < B:
                    dp[i][j + 1][k + 1] = max(dp[i][j + 1][k + 1],
                                               cur + g[j] * b[k])

    print(ans)

if __name__ == "__main__":
    solve()
```该代码直接反映了 DP 定义。 三重嵌套循环枚举所有前缀状态，确保考虑每个可达配置。 每个转换完全对应于选择下一个未使用的两种颜色的元素并形成一个矩形。 

变量`ans`是必需的，因为最优解决方案可能不会使用所有元素，因此我们跟踪所有中间状态的最佳值，而不仅仅是`dp[R][G][B]`。 

一个常见的陷阱是忘记允许未使用的元素。 无需更新`ans`在每个状态下，算法都会错误地强制完全消耗所有前缀。

 ## 边缘情况

 当一种颜色的值非常大而其他颜色的值虽小但数量众多时，就会出现微妙的边缘情况。 DP 正确地处理了这个问题，因为它可以选择通过向不消耗该颜色的方向移动来完全跳过某些配对。 

例如，如果红色包含`[100, 1]`， 绿色的`[2]`和蓝色`[50]`，DP 探索两种配对`100×2 + 1×50`和`100×50`，最终选择最佳组合。 贪婪的方法可能会配对`100×2`首先并失去可能性`100×50`，但 DP 保留两条路径。 

另一个边缘情况是当元素不被使用时是最佳的。 答案不一定`dp[R][G][B]`，因为消耗所有元素会强制进行次优配对。 所有状态的运行最大值确保考虑提前停止的配置，例如仅使用每种颜色中最大的几个元素并丢弃其余元素。
