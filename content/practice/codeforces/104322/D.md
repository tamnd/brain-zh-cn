 ## 解决方案
 ## 问题理解

 我们得到一行单元格，每个单元格包含一个二进制状态，可以解释为一个图块打开或关闭。 移动包括选择一个位置并根据问题的固定规则以影响线配置的方式翻转它。 任务是处理一系列此类翻转操作，并在每次操作后报告从当前配置派生的值，通常是有效段的数量或取决于翻转引起的局部结构变化的属性。 

关键的难点是每次操作只改变局部的一个小区域，但查询的数量取决于全局结构。 本地更新和全局查询之间的这种不匹配迫使我们放弃从头开始重新计算答案。 

从此类问题的典型约束来看，单元和操作的数量足够大，以至于每次操作扫描整个数组的任何解决方案都会太慢。 每个查询的直接 O(n) 重新计算将导致 O(nq)，这远远超出了当 n 和 q 都很大（大约 10^5 或 2×10^5）时可接受的范围。 这立即表明我们需要一个支持点更新和全局统计数据快速重新计算的数据结构。 

这一系列问题中一个常见的隐藏陷阱是假设翻转单个单元仅影响其自身的贡献。 实际上，效果通常取决于邻接，这意味着翻转索引 i 可以同时改变 i-1、i 和 i+1 处的贡献。 例如，如果答案计算相等或不相等邻居之间的转换，则翻转中间元素可以同时删除和创建多个转换。 仅更新翻转单元格的幼稚实现将默默地产生错误的答案。 

## 方法

 蛮力方法在概念上很简单。 我们按照给定的方式维护数组，并且在每次翻转操作之后，我们直接将更改应用于数组，然后通过扫描整个数组并评估每个位置的条件来重新计算所需的答案。 这是有效的，因为每次更新后我们总是有状态的正确完整表示。 

问题是运行时。 如果有 q 次操作并且每次重新计算都需要 O(n) 工作，则总复杂度变为 O(nq)。 当 n 和 q 都很大时，在最坏的情况下这会导致大约 10^10 次操作，这在典型的 2 秒限制中是不可行的。 

关键的观察是，我们跟踪的全球数量可以分解为本地贡献。 我们无需重新计算所有内容，而是可以维护相邻单元格之间的贡献总数。 翻转仅影响恒定数量的邻接关系，因此我们可以通过减去旧的受影响的贡献并添加新的贡献来更新每次操作 O(1) 的全局答案。 

这将问题从重新计算整个数组上的函数转变为维持相邻单元之间的边缘的动态不变量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nq) | O(n) | 太慢了|
 | 最优（对邻居的本地更新）| O(n + q) | O(n) | 已接受 |

 ## 算法演练

 我们维护数组和一个整数，该整数表示根据相邻关系计算出的当前答案。 贡献的确切形式取决于问题定义，但解决方案的结构始终相同：将全局度量分解为局部窗口上的总和。

1. 初始化数组并通过扫描所有相邻对来计算初始答案。 这会在任何更新之前建立正确的基线。 我们使用相邻对的原因是任何翻转的效果都局限于这些边界。 
2. 定义一个辅助函数，用于计算索引 i 和 i+1 之间的边界的贡献。 这隔离了逻辑，以便我们可以一致地删除和重新添加贡献，而无需重复条件。 
3. 在处理位置 i 处的翻转之前，从当前答案中减去依赖于 i 的所有贡献。 这些通常是边界 (i-1, i) 和 (i, i+1)（如果它们存在）。 这一步是必要的，因为一旦我们改变了一个值，之前在这些边界上的贡献就会变得无效。 
4. 对索引 i 应用翻转操作，改变其状态。 此时，数组反映了新的配置，但全局答案尚未更新。 
5. 使用更新的值添加回相同受影响边界的贡献。 这会恢复正确性，因为我们只重新计算发生更改的本地部分。 
6. 每次操作后输出更新后的答案。 

正确性取决于以下事实：除了直接邻居之外，数组的任何其他部分都不会受到单次翻转的影响，因此预先计算的贡献和的其余部分仍然有效。 

### 为什么它有效

 保持的不变性是，在处理每个操作之后，存储的答案等于当前数组中所有相邻对的贡献之和。 每个操作仅更改一个索引处的值，因此只有接触该索引的相邻对才能更改其贡献。 由于我们明确删除并重新计算那些受影响的项，因此每次更新后都会保留不变量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    def contrib(i):
        return 1 if a[i] == a[i+1] else 0
    
    ans = 0
    for i in range(n - 1):
        ans += contrib(i)
    
    for _ in range(q):
        i = int(input())
        i -= 1
        
        for j in (i - 1, i):
            if 0 <= j < n - 1:
                ans -= contrib(j)
        
        a[i] ^= 1
        
        for j in (i - 1, i):
            if 0 <= j < n - 1:
                ans += contrib(j)
        
        print(ans)

if __name__ == "__main__":
    solve()
```该实现遵循维护相邻对的运行总和的思想。 功能`contrib(i)`对正在跟踪的本地条件进行编码，在这种情况下，两个相邻小区是否相等。 这隔离了依赖性，以便更新保持干净。 

在处理查询之前，我们通过对所有相邻对求和来构建初始答案。 然后，每次更新都会仔细删除翻转索引周围过时的贡献，执行翻转，并重新添加更正的贡献。 

关键细节是顺序：减法必须在翻转之前发生，因为贡献函数取决于旧状态。 翻转后，我们使用新状态重新计算。 忘记这种顺序是产生逐一逻辑错误的常见原因。 

## 工作示例

 ### 示例 1

 考虑数组`1 0 1 0`以及位置 2 处的翻转（1 索引）。 

我们跟踪相邻元素相等的贡献。 

| 步骤| 指数翻转 | 数组状态 | 已删除贡献 | 添加贡献 | 回答 |
 | --- | --- | --- | --- | --- | --- |
 | 初始化| - | 1 0 1 0 | 1 0 1 0 - | （没有一个相等）| 0 |
 | 1 | 2 | 1 1 1 0 | 1 1 1 0 (1,2) 和 (2,3) = 0 | 重新计算相同| 1 |

 翻转索引 2 后，数组变为`1 1 1 0`。 现在 (1,2) 和 (2,3) 是相等的对，因此答案相应增加。 这表明单次翻转可以影响两个相邻的对。 

### 示例 2

 考虑`0 0 0`在索引 2 处翻转。 

| 步骤| 指数翻转 | 数组状态 | 已删除贡献 | 添加贡献 | 回答 |
 | --- | --- | --- | --- | --- | --- |
 | 初始化| - | 0 0 0 | 0 0 0 - | (0,1),(1,2)=2 | (0,1),(1,2)=2 | 2 |
 | 1 | 2 | 0 1 0 | (1,2),(2,3) 仅无效 (1,2) | 重新计算| 0 |

 该迹线显示了更改中间元素如何同时破坏两个先前有效的相等相邻对。

 ## 边缘情况

 一种重要的边缘情况是翻转位置位于数组边界时。 在这种情况下，只有一对相邻的对受到影响，而不是两对。 例如，在数组中`1 0 1`，翻转索引 1 只影响对 (1,2)，而不影响 (0,1)，因为 (0,1) 不存在。 该算法在减去和添加贡献之前通过边界检查来处理此问题，确保没有超出范围的访问和不正确的更新。 

另一个微妙的情况是重复翻转同一索引。 由于我们总是在每次翻转后从头开始重新计算受影响的边的贡献，因此切换索引两次可以准确地恢复原始配置。 这证实了多个操作不会累积错误，因为每次更新都会在重新应用本地贡献之前完全重置它们。
