 ## 解决方案
 ## 问题理解

 我们得到一个有向图，其中每个节点代表一个谜题。 每个节点都以零“能量”开始，并且每个节点都有一个阈值。 一旦节点累积的总能量达到或超过其阈值，该节点就会解锁。 

能量出现的唯一方式是通过未锁定的节点。 当节点解锁时，它立即开始向其所有传出邻居发送能量。 每条传出边都有一个行程时间，因此如果节点 u 在时间 T 解锁，则每条带有延迟 w 的边 u → v 在时间 T + w 正好向 v 贡献一个单位的能量。 如果 v 从不同的邻居或不同的路径接收到多个这样的贡献，它们都会累积。 

在这个传播系统之上，还有一些特殊的事件。 每个事件都会选择一些节点，并在特定时间强制它们的阈值变为零。 一旦节点的阈值变为零，它就会立即解锁，无论到目前为止它接收了多少能量。 

任务是计算每个节点最早解锁的时间。 如果某个节点永远无法解锁，则答案为 -1。 

约束很大：最多 100,000 个节点和最多 1,000,000 条边。 这立即排除了任何重新计算每个节点的全局状态或逐时间步模拟时间的情况。 该结构表明，当其源节点解锁时，每条边只能“激活”一次，因此任何解决方案都必须仔细确保每个节点被处理一次，并且每条边被放松一次。 

能量如何积累会出现一个微妙的困难。 节点不会由于单个最短路径而解锁，而是由于达到传入能量事件的阈值计数。 这与经典的最短路径问题不同，迫使我们跟踪每个节点的多个到达时间，而不仅仅是最佳的到达时间。 

打破幼稚传播的一种边缘情况是，节点具有正阈值，但稍后收到许多缓慢的贡献，同时也较早发生强制重置事件。 

例如，考虑阈值为 2 的节点 v。它在时间 100 和 200 处接收两个传入贡献。它还在时间 50 处强制重置。正确答案是 50，因为它在重置时间立即解锁。 仅考虑能量到达的简单方法会错误地输出 200。 

当节点最初的阈值为零时，会发生另一种故障情况。 它应该在时间 0 解锁，但如果解算器错误地将激活延迟到第一个传入边缘处理，它将高估所有下游时间。 

## 方法

 直接模拟将尝试随着时间的推移维持每个节点的当前能量，并重复处理最早的下一个事件。 人们可以想象一个全局事件队列，其中包括“能量到达”和“解锁事件”，并在达到阈值时更新节点。 问题在于，每个节点最多可以接收其无穷数量的能量贡献，并且每个贡献取决于其源何时解锁。 由于解锁本身取决于累积的贡献，因此系统变得相互依赖。 

如果我们忽略这种耦合并假设到达时间固定，则每个节点 v 将简单地收集所有传入时间 T[u] + w 并取 ai[v] 第最小的一个。 该部分可以通过每个节点的堆进行管理。 真正的困难是 T[u] 事先不知道。 

关键的观察是每个节点都有一个最终解锁时间，并且一旦节点解锁，它就会恰好发射一次能量。 这使我们能够将解锁事件视为不可逆的状态更改，类似于 Dijkstra 算法，其中每个节点都会最终确定一次。

因此，我们维护了两个可以触发解锁的独立机制。 第一个是来自刷新的强制解锁时间。 第二个是收集到足够的能量到达的时间。 每次我们最终确定节点的解锁时间时，我们都会通过生成新的能量到达事件将其影响传播到邻居。 

这自然会导致针对候选解锁时间的最佳优先处理策略。 每当我们发现节点的潜在解锁时间（无论是刷新还是达到阈值）时，我们都会将其推入全局优先级队列。 最小的候选时间始终是下一个要敲定的节点，一旦敲定，就成为真正的解锁时间。 

为了支持基于阈值的解锁，每个节点都维护一个结构，用于跟踪其最小传入到达时间直至其所需的计数。 固定大小 ai[v] 的最大堆就足够了，因为它始终保留迄今为止看到的 ai[v] 最小到达时间，并且该堆的顶部是当前候选阈值时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 能量随时间的暴力模拟 | O(时间 · n + m 时间步) | O(n + m) | 太慢了|
 | 具有阈值跟踪功能的事件驱动 Dijkstra | O((n + m) log n) | O((n + m) log n) | O(n + m) | 已接受 |

 ## 算法演练

 我们围绕候选解锁事件的全局优先级队列和跟踪传入能量到达的每节点结构构建解决方案。 

1. 对于每个节点，计算其最早可以从刷新中强制解锁的时间。 如果节点没有刷新，则该值为无穷大。 初始阈值为零的节点被视为强制解锁时间为零。 这为每个节点提供了一个初始候选解锁事件。 
2. 使用所有对 (forced_time[v], v) 初始化优先级队列。 这代表节点无需等待能量传播即可解锁的所有直接方式。 
3. 对于每个节点 v，维护一个最大堆，最多存储 ai[v] 个最小传入能量到达时间。 这种结构使我们能够确定 v 何时收到足够的能量来通过传播解锁。 
4.维护一个数组，存储每个节点当前已知的最佳解锁时间，初始化为其强制解锁时间。 
5. 当优先级队列不为空时，提取时间最小的事件。 如果这个时间不比该节点已经最终确定的解锁时间更好，则丢弃它，因为已经处理了更好或相等的解锁。 
6. 否则，此时确定该节点。 这是节点真正解锁的时刻。 
7. 从这个新解锁的节点 u 开始，以权重 w 遍历所有出边 u → v。 对于每个这样的边，在时间 T[u] + w 处插入一个新的能量到达事件到 v 的堆中。 
8. 将到达插入到 v 的堆中后，如果堆大小超过 ai[v]，则删除最大元素，以便仅保留最小的 ai[v] 到达。 如果堆大小恰好变为ai[v]，则堆当前最大元素表示ai[v]第最小到达时间，这是通过能量的候选解锁时间。 将这个候选者推入全局优先级队列。 
9. 继续，直到处理完所有事件。 从未接收到足够到达且没有有限强制解锁时间的节点保持无穷大并输出为-1。 

正确性取决于每个节点在其最短可能解锁时间精确确定一次。 同一节点的任何后续候选者都是无关紧要的，因为它无法改进已经最终确定的状态。 堆不变量确保在任何时刻，候选的基于能量的解锁时间正是给定迄今为止所有已处理的到达的真实阈值穿越时间。 由于到达仅从最终确定的节点生成，因此对源的后续修正不能使先前生成的事件无效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

INF = 10**30

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))

    forced = [INF] * n

    # read refreshers
    for _ in range(k):
        tmp = list(map(int, input().split()))
        t = tmp[0]
        sz = tmp[1]
        ids = tmp[2:]
        for v in ids:
            v -= 1
            if t < forced[v]:
                forced[v] = t

    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, w))

    # best unlock time
    ans = [INF] * n

    # PQ of candidate unlock events
    pq = []

    # per node: store smallest ai[v] arrivals using max-heap (negated)
    heaps = [[] for _ in range(n)]

    # initialize forced unlocks
    for i in range(n):
        if forced[i] < INF:
            heapq.heappush(pq, (forced[i], i))
        if a[i] == 0:
            heapq.heappush(pq, (0, i))

    while pq:
        t, u = heapq.heappop(pq)
        if t >= ans[u]:
            continue

        ans[u] = t

        for v, w in g[u]:
            arr = t + w

            if a[v] > 0:
                heap = heaps[v]
                heapq.heappush(heap, -arr)
                if len(heap) > a[v]:
                    heapq.heappop(heap)

                if len(heap) == a[v]:
                    kth = -heap[0]
                    if kth < ans[v]:
                        heapq.heappush(pq, (kth, v))

    out = []
    for i in range(n):
        out.append(str(ans[i]) if ans[i] < INF else "-1")
    print(" ".join(out))

if __name__ == "__main__":
    solve()
```该代码区分了两种可以触发激活的机制：强制解锁时间和基于阈值的解锁时间。 优先级队列将两者合并为一个全局顺序，确保始终首先处理最早的解锁事件。 

每个节点维护一个最大大小为 ai[v] 的最大堆，这保证了堆根始终是当前 ai[v] 的最小到达时间。 这可以避免存储所有传入事件，这些事件在约束下会太大。 

一个微妙的点是，一旦节点最终确定，即使堆有所改进，后面的候选时间也会被忽略。 这是安全的，因为任何改进都必然大于或等于已选择的时间，因为队列按升序处理事件。

 考虑第二个示例，其中存在强制更新并且传播与它们相互作用。 

我们只跟踪前几个重要事件。

 | ---| ---| ---| ---| ---|

现在考虑传播主导的情况。 

| 步骤| 节点| 活动时间| 行动| 结果状态 |
 | ---| ---| ---| ---| ---|
 | 1 | 1 | 0 | 解锁源码| 节点 1 = 0 |
 | 2 | 1 → 2 | 1 | 到达 | 堆[2] = [1] |
 | 3 | 1 → 2 | 2 | 到达 | 堆[2] = [1,2] |
 | 4 | 2 | 2 | 达到第 k 个 | 节点 2 = 2 |

 | ---| ---| ---|
 | 时间 | O((n + m) log n + Σ ai log ai) | 每个节点最终确定一次，每个边处理一次，每次到达时进行堆操作 |

 ## 边缘情况

 关键的边缘情况是节点阈值为零时。 这样的节点必须在时间零解锁，即使没有边指向它。 在该算法中，这些节点被插入到时间为零的优先级队列中，确保它们充当初始传播源。 

另一种情况是当节点同时具有强制解锁和传入能量到达时。 该算法正确地处理了这个问题，因为它总是采用从优先级队列中弹出的最小事件。 如果能量将在时间 120 解锁它，但在时间 50 存在刷新，则队列首先处理 50 并提前完成节点，丢弃后面的候选时间。 

第三种情况是节点从未达到其阈值并且没有刷新。 这些节点永远不会将有限事件推入优先级队列，因此它们保持无穷大并正确输出-1。
