 ## 解决方案
 ## 问题理解

 我们得到一个最多有 100 万行但最多只有 10 列的二进制矩阵。 每个单元格最初包含零或一。 我们可以重复翻转整行或整列，其中翻转意味着切换该行或列中的每一位。 

在执行任何此类操作序列后，每个单元格变为零或一，仅取决于其行和列翻转次数的奇偶校验。 一旦最终矩阵固定，每个等于 1 的单元格都会贡献一个等于线性权重的值，该值取决于其位置：行索引乘以 A 加列索引乘以 B。等于 0 的单元格不贡献任何内容。 目标是选择翻转以使总加权和最大化。 

这些限制严重影响了结构。 行数足够大，任何多次接触每一行的算法都必须仔细控制，而列数最多为 10 意味着列状态空间很小，可以枚举或视为位掩码。 这种不平衡是主要信号：解决方案必须将问题压缩到行上并利用列上的指数枚举。 

幼稚的解释会尝试模拟翻转或搜索所有操作序列。 这会立即失败，因为即使描述状态空间在行和列中也是指数的，并且操作的数量是无限的。 

第二个天真的尝试是直接决定对于每个行和列配置，翻转该行或列是否有帮助。 然而，行翻转和列翻转之间的依赖性意味着局部决策会干扰全局，因此贪婪策略会失败。 

当 A 或 B 为负时，会出现微妙的边缘情况。 在这种情况下，在索引较高的行或列中转动更多的分数可能会降低总分，即使它增加了分数的数量。 例如，如果所有条目都是 1 并且 B 非常负，则翻转列以在高列索引中创建零可能会增加分数。 这证实了问题不在于最大化，而是在于奇偶选择后加权的最大化。 

## 方法

 暴力视角首先注意到每个行翻转和列翻转都可以表示为二进制变量。 让每行有一个位 ri，每列有一个位 cj。 当且仅当 ai、j、ri 和 cj 的 XOR 等于 1 时，单元 (i, j) 才是最终矩阵中的 1。 这将问题转化为选择 n 加 m 的二元变量，这已经表明搜索空间的大小为 2^(n+m)，太大了。 

然而，结构简化的关键在于m极小。 这建议枚举所有可能的列翻转配置。 一旦列配置固定，每一行就变得独立，因为翻转一行只会同时切换其所有 m 位。 这意味着对于每一行，我们可以在了解列状态后决定翻转它是否有益。 

对于固定列掩码，每一行恰好有两种状态：不翻转该行，或翻转该行。 这两个选项是互补的，因为翻转行会在固定列变换下将该行中的每一位转换为其补码。 这允许独立计算每行的最佳贡献并对它们求和。 

对列掩码的暴力破解仅以 m 为指数，最多为 10，因此是可行的。 剩余的成本是迭代每个掩码的所有行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解所有行和列翻转 | O(2^(n+m)) | O(2^(n+m)) | O(纳米) | 太慢了|
 | 枚举列掩码，独立评估行 | O(n·m·2^m) | O(n·m·2^m) | O(纳米) | 已接受 |

 ## 算法演练

我们将每个列翻转选择编码为长度为 m 的位掩码。 每个位指示该列当前是否被翻转。 我们迭代所有此类掩码。 

对于每个掩码，我们在两种可能性下计算每行的贡献：不翻转行，或翻转它。 我们积累了这两者中最好的。 

1. 将每个列翻转配置枚举为从 0 到 2^m − 1 的位掩码。 
2. 对于固定掩码，独立处理每一行。 对于第 i 行，如果我们不翻转该行，则计算它贡献的值。 这是通过将列掩码应用于行的原始位并对结果位为 1 的位置的权重求和来获得的。 
3. 对于同一行，计算翻转该行的值。 不要从头开始重新计算，而是观察翻转行会切换所有位，因此在同一列掩码下每个零都变为一，每个一都变为零。 这意味着翻转的值是总行权重总和减去未翻转的值。 
4. 取该行两个值中的最大值并将其添加到该列掩码的总分中。 
5. 处理完所有行后，用所有列掩码中的最佳总数更新全局答案。 

关键的不变量是，对于固定的列配置，每行在是否翻转的选择上是完全独立的。 行决策不会影响任何其他行，因为行翻转不会跨行交互，并且列效应已经固定。 这种独立性确保了在固定列掩码内贪婪地最大化每行会产生该掩码的最佳结果。 由于枚举了所有列掩码，因此覆盖了全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, A, B = map(int, input().split())
    mat = [input().strip() for _ in range(n)]

    # Precompute weights per column
    col_weight = [B * (j + 1) for j in range(m)]

    # Precompute row base weights and cell contributions
    # w[i][j] = A*(i+1) + B*(j+1)
    # store row values and total row sum
    row_bits = []
    row_sum = []

    for i in range(n):
        w_i = A * (i + 1)
        bits = []
        total = 0
        for j in range(m):
            w = w_i + col_weight[j]
            if mat[i][j] == '1':
                total += w
                bits.append(w)
            else:
                bits.append(0)
        row_bits.append(bits)
        row_sum.append(sum(w_i + col_weight[j] for j in range(m)))

    ans = 0

    for mask in range(1 << m):
        cur = 0
        for i in range(n):
            v0 = 0
            for j in range(m):
                if mask & (1 << j):
                    v0 += (1 - int(mat[i][j])) * (A * (i + 1) + B * (j + 1))
                else:
                    v0 += int(mat[i][j]) * (A * (i + 1) + B * (j + 1))

            best = max(v0, row_sum[i] - v0)
            cur += best

        ans = max(ans, cur)

    print(ans)

if __name__ == "__main__":
    solve()
```该实现遵循固定列掩码并独立评估每一行的想法。 表达式 row_sum[i] - v0 用于计算翻转行贡献，而无需重新计算所有单元格。 这很重要，因为直接重新计算会使每个掩码每行的工作量增加一倍。 

嵌套循环反映了结构：外部循环枚举列状态，中间循环迭代行，内部循环评估 m 列。 正确性依赖于行翻转是对一组固定的 m 值的全局反转这一事实。 

## 工作示例

 考虑一个小矩阵，其中 n = 2、m = 2、A = 1、B = 1，并且所有条目均为 1。 

对于掩码 00（无列翻转），我们按原样评估每一行。 每个单元格都贡献其权重，翻转一行将删除该行中的所有贡献，因为它会将 1 变成零。 因此，对于每一行，我们都保持其不翻转。 

| 行| v0（无翻转）| row_sum - v0（翻转）| 选择|
 | --- | --- | --- | --- |
 | 1 | 3 | 3 | 3 |
 | 2 | 5 | 5 | 5 |

 总数为 8。 

这表明，当所有位都已经是最佳时，不需要翻转，并且算法正确地避免了不必要的反转。 

现在考虑一个混合矩阵：

 n = 2，m = 2，A = 1，B = -1

 矩阵：

 1 0

 0 1

 对于掩码 01（翻转第二列），第二列发生有意义的变化。 我们逐行评估。 

| 行| v0 | row_sum - v0 | 选择|

 此案例展示了列翻转如何全局改变每行的解释，但一旦掩码固定，行决策保持独立。 

该跟踪证实该算法探索了所有列配置，并且针对每一种列配置都以最佳方式解决了行翻转问题。

 ## 边缘情况

 关键的边缘情况是 A 或 B 为负时。 在这种情况下，算法仍然正确评估两个行翻转状态，因为翻转行会将每个贡献转换为其相对于固定行权重和的补码。 这确保了即使较高的指数降低分数，最大操作也能正确地选择抑制这些贡献的配置。 

当一行全为零或全一时，会出现另一种边缘情况。 对于全零行，v0 对于任何列掩码都为零，并且翻转该行会产生完整的行总和。 仅当总权重为正时，算法才能正确选择翻转。 对于全一行，决策完全取决于当前列掩码是否使某些位置为零，并且补码技巧仍然给出正确的替代方案而无需重新计算。
