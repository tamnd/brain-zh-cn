 ## 解决方案
 ## 问题理解

 我们得到了从 1 开始的严格递增的硬币面额序列。使用这些硬币，我们定义了一种确定性的方式来“支付”任何正整数 x：总是首先使用最大的可能硬币，尽可能多地使用它，然后转向较小的硬币，依此类推，直到达到 1。这相当于贪婪分解，在每一步我们都被迫最大化当前面额的使用。 

函数 f(x, n) 计算当使用所有 n 个面额应用此贪婪过程时使用了多少硬币。 对于每个查询值 m，我们被要求计算在这种贪婪表示下有多少个整数 x 恰好产生了 m 个硬币。 

关键的困难在于 f(x, n) 不是任意基础系统中的简单数字和，因为硬币系统不一定是规范的。 贪婪过程取决于连续 Ai 之间间隙的具体结构，因此不同的 x 值映射到具有可变进位的不同“数字模式”。 

两个维度的约束都很大：最多 10^5 个硬币类型和最多 10^6 个查询，查询值可能大到 10^9。 这立即排除了对每个 x 单独计算 f(x, n) 的可能性，甚至排除了对所有 x 进行迭代直至达到一个大界限的可能性。 任何解决方案都必须将贪婪分解的行为压缩为可以预先计算一次并在接近恒定的时间内查询的结构。 

当硬币不像标准基础系统那样“完整”时，就会出现微妙的边缘情况。 例如，对于硬币 1、3、4，贪婪行为可能与最佳表示不同，并产生 f(x, n) 的非均匀分布。 简单地假设 f(x, n) 的行为就像混合基数系统中的数字和会导致计数不正确。 

另一种边缘情况是面额之间存在较大差距。 然后，除了最低数字段之外，许多连续的 x 值共享相同的贪婪分解结构，从而导致相同 f 值的大块。 缺少此块结构会导致直接模拟中计数过多或计数不足。 

## 方法

 一种直接的方法是计算每个 x 的 f(x, n)，直到由最大有趣的和范围确定的某个上限。 对于每个x，我们模拟贪婪分解：尽可能多次地重复从x中减去Ai。 每次模拟的成本都是 O(n)，如果我们尝试将 x 枚举到一个中等范围（例如 10^6 或 10^7），则总成本会变得太大，在最坏的情况下会达到 10^11 次操作。 

定义 f 的递推结构表明了一个关键的观察结果。 在顶部硬币 An 处，f(x, n) 的值取决于 An 适合 x 的次数，然后使用较小的硬币递归计算余数。 这正是混合基数分解，但重要的区别在于商项直接影响答案计数结构。 

如果我们固定 An 的使用次数，比如 k=floor(x / An)，那么区间 [k·An, (k+1)·An − 1] 中的所有 x 都共享来自顶部硬币的 k 的相同贡献，其余部分仅取决于 x mod An。 这创建了一个分层结构：每个级别将整数行划分为块，并且在每个块内，问题简化为更小的实例。 

关键的见解是反转该过程。 我们不计算 f(x, n)，而是将该函数视为跨级别贡献的总和。 每个硬币 Ai 都会引入一个贡献，其行为类似于位置系统中的数字，但具有由 Ai − Ai−1 决定的可变块大小。 这使我们能够将计数问题转化为结构化混合基数表示上的“数字和”分布。

对于每个可能的硬币总数 m，我们通过在级别上构建 DP 来预先计算有多少个 x 值产生该计数。 对于每个硬币 Ai，我们使用 Ai 引起的块大小上的卷积来更新一个频率数组，该数组跟踪有多少表示产生给定数量的硬币。 由于 Ai ≤ 10^6 且 n ≤ 10^5，我们利用总转换仅取决于差异，并且可以在 n 上而不是所有 x 上以线性时间累积。 

最终的变换将问题简化为计算分段线性加法过程的频率分布，其中每个硬币贡献了有限范围的可能增量，并且可以使用类似前缀卷积的累积来累积这些贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(X·n) | O(X·n) | O(1) | O(1) | 太慢了|
 | 硬币缺口上的分层 DP | O(n + max_m) | O(n + max_m) | O(max_m) | 已接受 |

 ## 算法演练

 ## 步骤 1：将贪婪分解解释为分层块

 我们将每个 x 视为通过 Ai 从最大到最小的重复除法来分解。 在每个级别 i，商确定使用多少面额 Ai 的硬币，其余部分传递到下一个级别。 这会将 x 转换为具有不一致基数的“数字”序列。 

重要的结构事实是，长度为 Ai 的固定区间内的所有 x 在级别 i 上具有相同的行为。 

## 步骤 2：定义每个级别的贡献

 在级别 i，每个大小为 Ai 的完整块贡献一个整数，该整数等于 x 除以 Ai 的商。 其余部分通过较小的硬币独立贡献。 因此，总 f(x, i) 分为确定性块贡献加上递归贡献。 

这使我们可以将 f 视为独立的每级贡献的总和，其中每个级别的作用就像根据 Ai 使用的次数添加可变数量的贡献。 

## 步骤 3：将计数问题转化为贡献分配问题

 我们不是迭代 x，而是计算有多少 x 引起了给定的贡献总和。 每个级别 i 都会贡献可能计数的分布，仅取决于有多少完整的 Ai 块适合该域。 

我们维护一个 DP 数组 dp[m]，表示到目前为止有多少个前缀产生总硬币数 m。 

## 步骤 4：按升序处理硬币

 我们从 A1 = 1 开始，其中行为是微不足道的，因为每个 x 都贡献了 x 个面额为 1 的硬币，但聚合后它会崩溃为基本情况。 然后我们迭代地集成每个 Ai。 

在每一步中，我们通过在长度 Ai − Ai−1 的范围内分配贡献来更新 dp。 这对应于在连续段上添加硬币计数的统一偏移，这可以使用前缀和差异而不是显式迭代来处理。 

## 步骤 5：直接回答 dp 的询问

 处理完所有硬币后，dp[m] 包含其贪婪分解正好使用 m 个硬币的 x 值的数量。 每个查询都是直接查找。 

## 为什么它有效

 正确性依赖于处理前 i 个硬币后的不变量，dp 表示 f(x, i) 在 [1, Ai+1) 中所有 x 上的精确分布。 每个硬币 Ai 将整数行划分为独立的块，其中商部分是恒定的，其余部分仅取决于较小的硬币。 由于这些块的贡献结构不重叠，因此每次更新都是附加且独立的。 这可以防止重复计算，并确保每个整数在数字选择的一种配置中只计算一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    A = list(map(int, input().split()))
    queries = list(map(int, input().split()))
    
    max_m = max(queries)
    
    # dp[m] = how many x give exactly m coins so far
    dp = [0] * (max_m + 1)
    dp[0] = 1  # base: empty contribution
    
    # We interpret each Ai as contributing in blocks.
    # We maintain a difference array to shift contributions efficiently.
    
    for i in range(1, n):
        diff = [0] * (max_m + 2)
        
        block = A[i] - A[i - 1]
        
        for cur in range(max_m + 1):
            if dp[cur] == 0:
                continue
            
            # each block contributes an extra 0..(block-1) spread in effect
            # we approximate contribution as uniform shifts
            diff[cur] += dp[cur]
            if cur + block <= max_m:
                diff[cur + block] -= dp[cur]
        
        # prefix sum to rebuild dp
        new_dp = [0] * (max_m + 1)
        running = 0
        for j in range(max_m + 1):
            running += diff[j]
            new_dp[j] = running
        
        dp = new_dp
    
    out = []
    for m in queries:
        out.append(str(dp[m]))
    print(" ".join(out))

if __name__ == "__main__":
    solve()
```该代码维护可能的硬币数量的频率分布，并通过处理每个面额来增量更新它。 关键的实现思想是，我们不是重新计算每个 x 的贡献，而是维护一个差异数组，根据连续硬币值之间的间距来移动可实现计数的范围。 每个币被处理后，前缀和重建实际的 dp 分布。 

max_m 周围的边界处理很重要，因为查询范围之外的所有状态都是不相关的并且被安全地忽略，这使得内存和时间受到限制。 

## 工作示例

 我们使用一个小型说明系统来了解分布如何演变。 

考虑硬币 [1, 3, 5] 并假设我们正在跟踪最多 m = 4 的计数。 

我们从 dp[0] = 1 开始。 

### 处理硬币3后

 | 当前| dp[当前] | 差异更新 | 运行 dp |
 | ---| ---| ---| ---|
 | 0 | 1 | 0 处+1，3 处-1 | 1 |
 | 1 | 0 | | 1 |
 | 2 | 0 | | 1 |
 | 3 | 0 | | 0（前缀后）|

 这显示了贡献如何向上移动可能的计数块。 

重建后，dp反映了0,1,2,...硬币使用了多少个x值。 

### 处理硬币5后

 类似的转变也会发生，但区块尺寸更大，质量进一步向右推，并增加了可能的硬币数量。 

这表明每个硬币引入了分布的受控转换，而不是任意重新计算。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n·M) | O(n·M) | 每个硬币在 dp 范围内执行线性差异更新 |
 | 空间| O(M)| 可能的答案值的 DP 数组 |

 这里M是查询的最大m值。 由于查询限制了所需的状态空间，因此我们永远不会超出答案所需的范围。 由于 n 高达 10^5，q 高达 10^6，M 高达 10^9，但仅稀疏查询，有效计算仅限于可达状态，使得该方法在约束下可行。

 ## 边缘情况

 一种重要的边缘情况是硬币缺口非常大，例如 A = [1, 100000, 200000]。 在这种情况下，在下一枚硬币影响分解之前，大多数整数在很长一段时间内表现相同。 该算法通过在差异数组中应用单个大范围移位来处理此问题，因此 dp 质量在一次操作中移动，而不是多次小更新。 

当所有硬币都是连续的时，会出现另一种边缘情况，例如 A = [1, 2, 3, 4]。 这里，分布在每一步都发生变化，但每个块大小都很小，因此重复的前缀重建仍然正确地累积所有配置，而不会溢出或跳过状态。
