 ## 解决方案
 ## 问题理解

 我们得到一个字符串，并要求计算在位置的间距限制下我们可以形成多少个不同的非空子序列。 子序列是通过从字符串中选取字符并保持其原始顺序来获得的，但我们不允许选取原始字符串中彼此太接近的字符。 更准确地说，如果我们连续选择两个位置，它们的指数必须相差超过$k$。 这意味着每个选定的字符必须至少$k+1$位于上一个选定字符之后的位置。 

输出是所有此类有效子序列中不同结果字符串的数量，以 998244353 为模。 

输入大小总共很大，字符串长度之和可达$10^6$。 这立即排除了任何显式枚举子序列的解决方案，因为即使没有约束，子序列的数量也呈指数级增长。 任何可接受的解决方案在总长度上都必须是线性的或接近线性的。 

一个不太明显的观察结果是，字符串中的实际字母不会影响此约束下不同子序列的计数。 该限制仅取决于选择的位置，而不取决于字符值。 由于每个选定的位置集唯一地确定一个子序列字符串，因此对不同子序列进行计数就相当于对有效索引集进行计数。 

如果尝试应用依赖于字符最后一次出现的标准不同子序列 DP，则会出现常见的失败情况。 例如，在像这样的字符串中`aaaaa`，天真的想法可能会尝试按字符合并贡献，但间距限制打破了这种结构。 该约束是位置性的，因此基于字符的 DP 会错误地折叠。 

当出现另一种边缘情况时$k = 0$。 那么任意两个连续选择的位置必须相差至少 1，这除了子序列规则本身之外没有任何限制。 正确的答案应该减少到计算所有非空子序列，即$2^n - 1$。 任何意外使用错误边界（例如将当前位置包含在前缀和中）的重复都会导致过度计数或产生自相关。 

## 方法

 暴力方法很简单：生成所有子序列并检查每个子序列是否满足间距规则。 对于每个子序列，我们在线性时间内验证相邻的选定索引。 由于有$2^n$子序列，即使对于$n = 30$，更不用说$10^6$。 失败来自于枚举位置子集，而位置子集呈指数增长。 

关键的见解是停止从角色角度思考，而是从最后一个元素的有效选择角度思考。 每个有效的子序列都可以通过其最后选择的位置来唯一地描述。 如果我们固定一个位置$i$作为最后一个元素，它之前的所有元素都必须形成一个以某个位置结束的有效子序列$j \le i-k-1$。 这会在前缀范围而不是组合结构上创建干净的递归。 

这将问题转化为针对具有前缀和的位置的简单动态规划。 我们维护在每个索引处或之前结束的有效子序列的数量，并使用范围总和来确保遵守间距约束。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n \cdot n)$|$O(n)$| 太慢了|
 | 前缀 DP |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将字符串索引从 1 到$n$。 让$dp[i]$表示最后选择的位置恰好是的有效子序列的数量$i$。 让$pref[i]$是$dp[1..i]$。 

1. 对于每个位置$i$，考虑开始一个仅包含以下内容的新子序列$S[i]$。 这会产生 1 个有效的子序列，结尾为$i$。 
2. 任何以以下结尾的更长子序列$i$必须来自之前的某个结束位置$j$，其中间距规则强制执行$i - j > k$, 等价地$j \le i - k - 1$。 这确保了最后一个间隙是有效的，并且较早的间隙已经由较早的状态强制执行。 
3、因此，我们设$dp[i] = 1 + pref[i-k-1]$, 治疗$pref[x] = 0$什么时候$x \le 0$。 
4.我们更新前缀和：$pref[i] = pref[i-1] + dp[i]$。 
5.最终答案是$pref[n]$，它聚合以任意位置结尾的所有有效子序列。 

### 为什么它有效

 每个有效的子序列都有一个唯一的最后选择的位置$i$。 一次$i$是固定的，剩余的前缀是任何有效的子序列，其最后一个位置遵守间距约束$i$。 递归将所有有效子序列按最后一个位置划分，没有重叠。 由于每个子序列在其终端索引处只计算一次，因此不会发生重复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()

        dp = [0] * (n + 1)
        pref = [0] * (n + 1)

        for i in range(1, n + 1):
            j = i - k - 1
            if j >= 1:
                dp[i] = (1 + pref[j]) % MOD
            else:
                dp[i] = 1

            pref[i] = (pref[i - 1] + dp[i]) % MOD

        print(pref[n] % MOD)

if __name__ == "__main__":
    solve()
```执行直接遵循递归。 唯一的微妙之处是处理索引，其中$i-k-1$变为非正数，在这种情况下，没有有效的先前子序列可以扩展。 前缀数组确保在恒定时间内计算范围总和。 

第二个微妙之处是字符串本身从未被使用。 尽管在输入中提供了有效子序列的数量，但它仅取决于允许的索引选择的结构，而不取决于字符标识。 这就是解决方案忽略的原因`s`完全。 

## 工作示例

 考虑一个例子$n = 5, k = 1$。 我们计算有效的子序列，其中所选位置必须相差至少 2。

 最终答案是 12。这反映了后面的位置有更多的自由度与前面的有效子序列组合，但仅限于那些足够远的子序列。 

现在考虑$n = 4, k = 2$，其中位置必须相差至少 3。

## 测试用例```python
import sys, io

MOD = 998244353

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()

        dp = [0] * (n + 1)
        pref = [0] * (n + 1)

        for i in range(1, n + 1):
            j = i - k - 1
            if j >= 1:
                dp[i] = (1 + pref[j]) % MOD
            else:
                dp[i] = 1
            pref[i] = (pref[i - 1] + dp[i]) % MOD

        out.append(str(pref[n] % MOD))
    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# minimum case
assert run("1\n1 0\na\n") == "1"

# all equal letters, k=0 => 2^n - 1 = 7 for n=3
assert run("1\n3 0\naaa\n") == "7"

# strict spacing
assert run("1\n4 2\nabcd\n") == "5"

# larger simple case
assert run("1\n5 1\nabcde\n") == "12"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 | n = 1，k = 0 | 1 | 最小子序列计数|
 | aaa，k=0 | 7 | 完整的后续生长|
 | abcd,k=2 | 5 | 强间距约束|
 | abcde，k=1 | 12 | 12 中间重叠行为|

 ## 边缘情况

 当$k = 0$，递归简化为经典的子序列计数。 例如与$n = 3$，我们有 dp 值$1, 2, 4$，总计为 7。该公式仍然有效，因为$i-k-1 = i-1$，因此每个位置正确地扩展了所有先前的子序列。 

什么时候$k \ge n$，两个位置不能同时选择。 每个 dp 条目都变为 1，因为不可能进行扩展。 例如与$n = 4, k = 5$，答案是4，对应于单独选择每个单独的位置。 

对于非常小的$n$， 例如$n = 1$，算法正确返回 1，无论$k$，因为唯一的子序列是单个字符。
