 ## 解决方案
 ## 问题理解

 有`n`商店。 店铺`i`有笔记本电脑成本`a_i`每个硬币，最多`b_i`那里可以买到笔记本。 每个世界都有完全相同的商店和库存，但金额不同`k`世界之间有所不同。 对于每个`m`在预算范围内，我们需要尽可能多地购买笔记本电脑。 

由于每台笔记本电脑都对答案贡献一个值，因此笔记本电脑的身份仅通过其价格来确定。 如果我们想最大限度地增加笔记本电脑的数量，最佳策略是首先使用最便宜的笔记本电脑。 因此，该问题相当于按价格对所有可用笔记本进行排序，并询问对于每个预算，可以提供该排序序列的前缀有多长。 

这些限制使得直接模拟变得不可能。 可以有`10^5`商店和`10^5`不同的世界，因此可以为每个世界独立处理每个商店`10^10`运营。 价格可以达到`10^9`并且预算可以达到`10^18`，因此需要 64 位整数运算。 Python 整数已经安全地处理这些值。 

在一些边缘情况下，粗心的实施可能会失败。 首先，预算可能会因商店库存而结束。 例如，```
1 1
10
6 2
```答案是`1`，因为一台笔记本的成本为 6，两台笔记本的成本为 12。仅考虑完整商店的实现将错误地返回`0`。 

其次，预算可以正好等于几台笔记本的成本：```
2 1
15
5 2
5 1
```三台笔记本电脑的价格都是 5，所以答案是`3`。 使用严格的二分查找`< budget`条件将错误地返回`2`。 

第三，非常大的预算可以买得起每台笔记本：```
2 1
100
3 2
7 4
```答案是`6`。 该算法必须允许搜索达到总库存，而不是假设在购买的前缀之后总是有买不起的商品。 

最后，几家商店可以有相同的价格。 例如，```
3 2
5 10
2 1
2 3
7 1
```对于预算`5`，四台笔记本电脑，每台售价 2 美元，并不都是买得起的，所以答案是`2`。 价格相同的商店必须被视为可互换，并且单独排序仍然会给出正确的结果。 

## 方法

 最直接的解决方案是按价格对商店进行排序，并针对每个世界，从最便宜到最贵进行扫描。 在每家商店，我们都会在剩余预算允许的情况下购买尽可能多的笔记本电脑，可能只购买部分可用库存。 这是正确的，因为用可用的更便宜的笔记本电脑替换购买的昂贵笔记本电脑永远不会减少我们可以买得起的笔记本电脑的数量。 

问题是重复扫描。 在最坏的情况下，`n = 10^5`和`m = 10^5`，因此扫描所有商店的每个预算需要花费`10^10`商店参观。 这远远超出了一秒竞赛解决方案的处理能力。 

关键的观察结果是，世界各地的商店都是相同的。 我们应该对通用价格结构进行一次预处理，而不是对每个预算重复相同的工作。 

按价格对商店进行排序后，定义一个前缀，其中包含前几家最便宜商店的所有笔记本。 对于每个这样的前缀，存储其笔记本总数及其总成本。 如果预算足够大，可以购买整个前缀，我们可以立即转向稍后的前缀。 一旦我们找到了第一家无法购买全部库存的商店，那么答案就已经由该商店决定了，我们只需要从它那里购买部分数量即可。 

这意味着每个查询都可以通过对总成本超过预算的第一个前缀进行二分搜索来回答。 前面的前缀是完全可以承受的。 剩下的钱可以买`remaining // price`下一家商店的笔记本电脑，以该商店的库存为上限。 

蛮力之所以有效，是因为按照价格递增的顺序购买商店会产生最优购买。 它失败了，因为它对每个世界都重复同样的遍历。 通过观察每个世界共享相同的排序存储，我们可以将重复的工作压缩到前缀数组中，并通过一次二分搜索独立地回答每个预算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n log n + mn)`|`O(n)`| 太慢了|
 | 最佳|`O(n log n + m log n)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 读取所有商店并按以下顺序排序`a_i`、笔记本价格。 必须始终首先考虑最便宜的笔记本电脑，因为在还有更便宜的笔记本电脑的情况下购买更昂贵的笔记本电脑并不能增加购买笔记本电脑的数量。 
2. 构建两个前缀数组。 让`cnt[i]`是第一个笔记本的总数`i`对商店进行排序，并让`cost[i]`是购买所有这些笔记本电脑的总价。 对于有价格的商店`a`和库存`b`，其对总成本的贡献为`a * b`。 
3. 对于每个有预算的世界`k`,二分查找最大前缀`i`满意的`cost[i] <= k`。 这可以准确地找出可用资金可以耗尽多少个完整商店。 
4.让`spent = cost[i]`。 如果`i`等于商店数量，每台笔记本都是买得起的，所以答案很简单`cnt[i]`。 
5. 否则，考虑商店`i`，这是第一家全部库存都太贵而买不起的商店。 还有`k - spent`可用的钱。 因为这家店里的每台笔记本价格都是一样的`a_i`，我们可以买`(k - spent) // a_i`其中。 我们不能超过它的库存，因此所取的数字是该商和中较小的一个`b_i`。 
6. 将部分购买的笔记本添加到`cnt[i]`并输出当前世界的结果。 

其起作用的原因是由以下不变量捕获的`cnt[i]`和`cost[i]`准确描述最便宜的购买方式`cnt[i]`可用库存中的笔记本电脑。 每个前缀都由最便宜的可用笔记本组成，因此任何包含超过`cnt[i]`笔记本电脑必须至少花费足够的钱才能达到下一个前缀。 一次`cost[i] <= k < cost[i+1]`，所有第一个`i`商店可以用完，但整个下一个商店无法购买。 由于下一家商店中的所有笔记本电脑价格相同，因此在剩余预算允许的情况下尽可能多地购买笔记本电脑可以得到最大可能的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    budgets = list(map(int, input().split()))

    stores = [tuple(map(int, input().split())) for _ in range(n)]
    stores.sort()

    prefix_count = [0] * (n + 1)
    prefix_cost = [0] * (n + 1)

    for i, (price, stock) in enumerate(stores, 1):
        prefix_count[i] = prefix_count[i - 1] + stock
        prefix_cost[i] = prefix_cost[i - 1] + price * stock

    answers = []

    for budget in budgets:
        lo = 0
        hi = n

        while lo < hi:
            mid = (lo + hi + 1) // 2
            if prefix_cost[mid] <= budget:
                lo = mid
            else:
                hi = mid - 1

        i = lo
        answer = prefix_count[i]

        if i < n:
            remaining = budget - prefix_cost[i]
            price, stock = stores[i]
            answer += min(stock, remaining // price)

        answers.append(str(answer))

    sys.stdout.write(" ".join(answers))

if __name__ == "__main__":
    solve()
```商店首先按以下顺序排序`(price, stock)`，尽管只有价格顺序很重要。 前缀数组有长度`n + 1`，有索引`0`代表一个空前缀。 这使得没有完整的商店是负担得起的边界情况是很自然的，因为`prefix_cost[0]`为零。 

对于每个预算，二分搜索都会维持以下条件：所有前缀等于或低于`lo`价格实惠。 上限是`n`，因为买下所有商店也许是可能的。 表达式`(lo + hi + 1) // 2`使中点向上偏置，这样可以防止无限循环`lo`和`hi`相差一。 

经过一番搜寻，`i`是符合预算的最大数量的完整商店。 如果`i == n`，没有下一个商店可以检查。 否则，`remaining`是非负的，因为`prefix_cost[i] <= budget`。 将其除以下一家商店的价格即可得出可以在该商店购买的额外笔记本电脑的最大数量。 

乘法`price * stock`可以大到`4 * 10^13`对于一家商店来说，总成本可能还要大得多。 Python 的任意精度整数处理所需的值而不会溢出。 

操作的顺序也很重要。 我们首先去除每个完全购买的更便宜商店的成本，然后仅将剩余的钱用于下一个价格水平。 没有理由放弃更便宜的笔记本电脑而选择更昂贵的笔记本电脑。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(n log n + m log n)`| 分拣成本`O(n log n)`，以及每个`m`预算使用二分搜索`n`前缀 |
 | 空间|`O(n)`| 排序后的存储和两个前缀数组包含`O(n)`价值观 |

 和`n, m <= 10^5`，预处理大致执行`10^5 log(10^5)`比较，并且查询执行另一个`10^5 log(10^5)`二分搜索迭代。 这完全在预期的规模之内，而`O(mn)`扫描最多需要`10^10`运营。

 ## 边缘情况

 当预算小于最便宜的笔记本时，二分查找返回前缀`0`。 例如，```
1 1
4
5 3
```两个都`prefix_cost[0] = 0`以及第一个完整的前缀成本计算`15`被考虑。 最大的负担得起的前缀是`0`， 所以`remaining = 4`， 和`4 // 5 = 0`。 答案是正确的`0`。 

当预算恰好足够一个完整的前缀时，`<=`比较是必要的。 为了```
2 1
10
5 2
8 1
```第一个前缀的成本正好`10`，所以二分查找返回`i = 1`。 答案是`2`。 使用`<`而不是`<=`会错误地丢弃一个负担得起的前缀。 

当预算落在下一家商店的库存范围内时，前缀搜索会故意在该商店之前停止。 为了```
1 1
10
6 2
```完整的前缀成本`12`，这太多了，所以`i = 0`。 剩余十枚金币购买`10 // 6 = 1`笔记本，给出正确答案`1`。 

当每台笔记本都买得起时，搜索就可以返回`i = n`。 为了```
2 1
100
3 2
7 4
```总成本是`34`，所以最大的可负担前缀是整个数组。 算法返回`prefix_count[2] = 6`并跳过部分存储计算，因为没有下一个存储。 

同等价格不需要任何特殊处理。 为了```
3 1
5
2 1
2 3
7 1
```排序按价格生产四本笔记本`2`，后面跟着一个价格`7`。 包含两个 Price-2 商店成本的前缀`8`，因此只有五个硬币时，算法会在完整的前缀之前停止并购买`5 // 2 = 2`笔记本。 答案是`2`。 无论具有相同价格的商店如何排序，相同的推理都有效。 

最后，大值必须被视为精确整数。 如果商店有价格`10^9`和库存`40000`，其总成本为`4 * 10^13`。 穿过`10^5`存储时，累计成本可以超过普通的 32 位和 64 位范围。 Python 整数避免溢出，并且前缀成本构造保留了二分搜索所需的精确值。
