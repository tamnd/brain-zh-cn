 ## 解决方案
 ## 问题理解

 我们有`n`南瓜，以及南瓜的大小`i`第一个南瓜是`a_i`。 两次操作就可以改变一个南瓜。 我们可以准确地添加`p`到它的大小，或者将它的大小乘以`k`。 第三步操作将南瓜变成一辆马车，但前提是它的大小恰好是`m`。 

对于每个初始南瓜，我们需要独立决定前两个操作的某些序列是否可以将其大小精确地转换为`m`。 输出包含`1`一个可用的南瓜和`0`否则。 

关键的困难在于操作可以交错。 例如，我们可以添加`p`, 乘以`k`， 添加`p`再次，并再次相乘。 对此类序列的直接搜索有太多的可能性。 

边界使得这一点特别具有限制性。 可以有`10^5`南瓜，所以算法可以执行甚至`O(n^2)`工作已经需要大约`10^10`运营。 目标大小和初始大小最多为`10^7`，这为线性算法留下了空间`m`，但是一个`O(n log m)`解决方案明显更好并且很容易满足极限。 自从`k >= 2`, 重复乘法只能发生`O(log m)`尺寸超过之前的次数`m`。 

有几种边界情况可能会欺骗粗心的实现。 如果`a_i > m`，答案立即`0`，因为每个可用的操作只会增加大小。 例如，与`1 3 2 7`和南瓜大小`9`，答案是`0`。 

南瓜可能已经达到目标大小。 和`1 5 2 10`和南瓜大小`10`，答案是`1`，因为在回车符之前允许进行零操作。 

乘法后的精确相等也很重要。 和`1 3 2 12`和南瓜大小`3`，乘以两次给出`12`，所以答案是`1`。 当下一次乘法超出时停止的实现`m`在相乘之前仍必须测试当前值。 

最后，具有相同的模余数`p`本身还不够。 相乘的值也不得超过`m`。 例如，与`1 6 2 10`和南瓜大小`6`， 两个都`6`和`10`模同余`2`，但答案实际上是`1`因为不需要乘法和两次加法`2`抵达`10`。 相比之下，对于`1 4 3 10`和南瓜大小`4`，余数条件成立，但相乘得出`12 > 10`，所以答案是`0`。 

## 方法

 直接的暴力解决方案可以将每个咒语视为添加之间的选择`p`并乘以`k`。 从南瓜开始，它递归地尝试这两个操作，而结果大小不超过`m`。 这是正确的，因为每个可能的有效序列仅包含这两个选择。 

问题在于序列的数量。 如果搜索探索`L`拼写位置，最多可以有`2^L`分支机构。 在最坏的情况下，`L`可以是以下顺序`m / p`，这可以是关于`10^7`。 一个界限，例如`2^10000000`显然不可能一一列举，即使是一个南瓜。 

暴力破解之所以有效，是因为它考虑了两个操作的每种可能的顺序，但从可达性的角度来看，大多数顺序是等效的。 关键的观察是每个乘法都可以在每个加法之前移动。 

假设一个序列包含一个加法`p`随后乘以`k`。 如果有`s`加法后的乘法，它对最终值的贡献是`p * k^s`。 我们可以删除它并执行，而不是在其原始位置执行该添加`k^s`补充者`p`在最后。 两个序列对最终大小的贡献完全相同。 

重复此转换会将所有乘法移至开头，并将所有加法移至末尾。 这是官方比赛分析中使用的中心简化。 

因此，如果南瓜一开始的大小`x`，每个可达到的目标都可以通过以下形式获得`x * k^t + q * p`对于一些非负整数`t`和`q`。 

对于固定数量`t`的乘法，我们首先达到`x * k^t`。 从那里开始，仅添加`p`保持。 这样的添加可以达到`m`完全当且仅当`m - x * k^t`是非负的并且可以被整除`p`。 

因此，对于每个南瓜，我们只需要尝试可能的值`t`。 自从`k >= 2`，值`x * k^t`呈指数级增长，因此只有`O(log m)`的可能性。 我们可以在恒定的时间内检查每一项。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 法术数量呈指数增长 | 有界搜索中的 O(m) 递归/状态深度 | 太慢了|
 | 最佳| O(n log m) | O(n log m) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读`n`,`p`,`k`,`m`以及初始南瓜尺寸的数组。 我们独立处理每个南瓜，因为应用于一个南瓜的咒语不会对另一个南瓜产生影响。 
2.对于当前南瓜尺寸`x`, 开始于`cur = x`。 这表示零乘法后获得的值。 
3. 在进行另一次乘法之前，检查是否`cur <= m`以及是否`(m - cur) % p == 0`。 如果这两个条件都成立，则南瓜就可以使用了。 我们可以先进行当前次数的乘法，然后重复加法`p`直到准确到达`m`。 
4. 如果检查失败，请更换`cur`经过`cur * k`并重复同时`cur * k <= m`。 仅当使南瓜保持在目标或低于目标时才考虑乘法，因为所有后续操作只会增加值。 
5. 如果检查了每个可能的乘法计数但没有找到有效的余数，则输出`0`为了这个南瓜。 
6. 对所有对象重复该过程`n`南瓜并打印结果的 0 和 1 序列。 

检查足够的原因是每个任意拼写序列都可以重新排列为所有乘法，然后是所有加法。 对于固定次数的乘法，唯一剩下的问题是与`m`是一个非负倍数`p`。 

### 为什么它有效

 考虑一个初始大小的南瓜`x`以及任何成功达到的序列`m`。 使用上述转换将每个添加移动到序列的末尾。 这保留了最终的大小，因此还有一个包含一些数字的成功序列`t`乘法后仅加法。 

经过这些乘法之后，南瓜就有了大小`x * k^t`。 其余操作添加`p`重复，所以最终值的形式`x * k^t + q * p`。 因此，对于某些情况，成功的序列恰好存在`t`,`x * k^t <= m`和`m - x * k^t`可以整除`p`。 

该算法会检查所有可能的情况`t`为此`x * k^t <= m`。 当条件满足时它会准确地接受，因此它不会错过一个有效的南瓜或接受一个不可能的南瓜。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, p, k, m = map(int, input().split())
    a = list(map(int, input().split()))

    ans = []

    for x in a:
        cur = x
        possible = False

        while cur <= m:
            if (m - cur) % p == 0:
                possible = True
                break

            if cur > m // k:
                break

            cur *= k

        ans.append(1 if possible else 0)

    print(*ans)

if __name__ == "__main__":
    solve()
```外循环处理每个初始南瓜一次。 为了那个南瓜，`cur`始终是经过一定次数的乘法之后和任何最终加法之前的大小。 因此，第一个检查恰好对应于一个候选值`t`。 

表达式`(m - cur) % p == 0`仅在之后使用`cur <= m`。 如果没有边界检查，负差可能会意外地满足整除性，即使南瓜永远不会减少到`m`。 

条件`cur > m // k`是决定下一个乘法将超过的安全方法`m`。 写作`cur * k <= m`在 Python 中也是正确的，因为 Python 整数不会溢出，但是`m // k`避免构建已知太大的值。 它还使边界条件变得明确。 

在乘法之前检查当前值。 这可以处理两个`x == m`以及正确的乘法次数恰好是当前迭代次数的情况。 在检查当前值之前停止会错误地拒绝此类南瓜。 

该解决方案不需要显式地计算所需的添加量。 一次`m - cur`是一个非负倍数`p`，执行许多加法达到`m`确切地。

 ## Edge Cases

 当初始南瓜大于`m`，算法立即进入循环条件`cur > m`，所以它不执行任何转换并返回`0`。 为了`1 3 2 7`和`a = 9`，这给出了`0`，这是必要的，因为加法或乘法都不能减小大小。 

当南瓜已经等于`m`，第一次迭代检查`(m - cur) % p`，即`0`。 算法返回`1`无需应用任何操作。 为了`1 5 2 10`和`a = 10`，答案是`1`。 

当乘法正好落在`m`，算法必须检查乘法后的值。 为了`1 3 2 12`和`a = 3`，检查的值为`3`,`6`， 和`12`。 在`12`，与目标的差异为零，所以答案是`1`。 

当乘法会跳过`m`，不得执行。 考虑`1 4 3 10`和`a = 4`。 当前值`4`有差异`6`，它不能被整除`4`，而下一个值将是`12 > 10`。 搜索停止并返回`0`。 

当有效路线在加法之前使用乘法时，模块化测试会找到它。 为了`p = 3`,`k = 2`,`m = 7`， 和`a = 2`，初始值`2`给出`7 - 2 = 5`，它不能被整除`3`。 经过一次乘法后，`cur = 4`， 和`7 - 4 = 3`可以整除`3`。 实际的顺序是`2 -> 4 -> 7`，所以算法正确返回`1`。 

该实现还无需任何特殊处理即可处理重复值。 每次出现都会单独检查，并针对相同的参数和相同的初始大小收到相同的结果。 这保留了所需的输出顺序。
