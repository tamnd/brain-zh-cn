 ## 解决方案
 ## 问题理解

 Katya 有两种衣服：T 恤和牛仔裤。 她收拾行李`n`T 恤和`m`牛仔裤，而她旅行时已经穿了一件额外的 T 恤和一条额外的牛仔裤。 于是，在训练营期间，她`n + 1`不同的T恤和`m + 1`提供不同的牛仔裤。 

她每天必须选择一件 T 恤和一条牛仔裤。 同一件完整的服装不能出现在不同的两天。 允许将 T 恤与不同的牛仔裤重复使用，也允许将牛仔裤与不同的 T 恤重复使用。 

输入包含`k`，营地天数，然后是`n`和`m`，装进行李箱的T恤和牛仔裤的数量。 我们需要打印`Yes`是否可以每天选择不同的全套服装，以及`No`否则。 

关键的限制是`k`可以大到`10^9`， 尽管`n`和`m`至多是`1000`。 这立即表明模拟日子是不可取的。 即使每天只执行恒定工作的算法也可能需要多达十亿次迭代。 另一方面，服装类型的数量足够小，可以直接计算不同组合的总数。 

有几种边界情况可以欺骗仅计算手提箱中装的衣服的解决方案。 例如，`1 0 0`必须产生`Yes`，因为 Katya 已经穿的一套衣服仅适用于唯一的露营日。 一种解决方案仅使用`n * m`会错误地获得零可能的服装。 

输入`2 0 0`必须产生`No`。 Katya总共只有一件T恤和一条牛仔裤，所以完整的服装只有一套。 第二天必然会重复这样的事情。 

另一个有用的边界情况是`2 1 0`。 总共有两件T恤和一条牛仔裤，正好是两套不同的衣服，所以答案是`Yes`。 之间的区别`n`和`n + 1`，和之间`m`和`m + 1`，是必不可少的。 

## 方法

 直接的暴力解决方案可以明确地为每个人生成服装`k`天并跟踪哪些对已被使用。 这是正确的，因为每个生成的对都可以根据之前的选择进行检查，并且当没有未使用的对时，该过程就会失败。 然而，在最坏的情况下，它需要处理最多`10^9`天。 即使哈希集提供平均恒定时间插入和查找，这也远远超出了一秒竞赛限制。 将每件新服装与所有以前的服装进行比较的版本甚至更糟糕，达到`O(k^2)`比较。 

问题的结构让我们完全避免构建任何装备。 一旦卡蒂亚有了`n + 1`T 恤和`m + 1`牛仔裤，每件T恤都可以搭配每条牛仔裤。 乘法原理准确给出`(n + 1) * (m + 1)`独特的完整服装。 

要求只是至少有`k`不同的服装`k`天。 如果可用组合的数量至少为`k`，我们可以选择任何`k`不同的对。 如果规模较小，则无法进行任何安排，因为首先就没有足够的独特服装。 

蛮力方法之所以有效，是因为它明确地探索了可用的组合，但会失败，因为天数可能很大。 只有可能对的总数才重要这一观察结果将整个问题简化为一次乘法和一次比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 集合的 O(k) 或直接比较的 O(k²) | O(k) | 太慢了|
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`k`,`n`， 和`m`。 这两个服装类别包括已穿着的物品，因此可用数量为`n + 1`T 恤和`m + 1`牛仔裤。 
2. 计算`(n + 1) * (m + 1)`。 这是不同的完整服装的数量，因为每件 T 恤都可以与每条牛仔裤独立组合。 
3. 将此数字与`k`。 如果至少是`k`， 打印`Yes`，因为我们可以选择`k`不同的组合。 否则，打印`No`，因为有些服装必须重复。 

乘法背后的推理是该解决方案的中心不变量：由一件特定的 T 恤和一条特定的牛仔裤组成的每双都恰好代表一套完整的服装，并且每一种可能的完整服装都由这样的一套恰好代表。 

### 为什么它有效

 有`n + 1`可能的 T 恤和`m + 1`可能的牛仔裤。 对于每件固定的 T 恤，正好有`m + 1`牛仔裤的选择，所以有`(n + 1) * (m + 1)`独特的完整服装。 需要有效的时间表`k`不同的服装，并且当可用服装的数量至少为`k`。 该算法精确地检查了这个条件，因此它返回`Yes`正是针对可行的情况。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

k, n, m = map(int, input().split())

outfits = (n + 1) * (m + 1)

print("Yes" if outfits >= k else "No")
```输入由一行组成，因此一次调用`input()`就足够了。 我们给两者加一`n`和`m`因为 Katya 旅行时穿的 T 恤和牛仔裤在营地期间也可以买到。 

乘法在比较之前执行。 Python 整数具有任意精度，尽管这里的实际乘积最多是`1001 * 1001`，因此即使在具有固定宽度整数类型的语言中，整数溢出也不是问题。 

比较使用`>=`， 不是`>`。 如果有与露营日一样多的独特服装，那么每天都可以收到独特的服装，所以答案一定是`Yes`。

## 测试用例```python
import sys
import io

def solve():
    input = sys.stdin.readline
    k, n, m = map(int, input().split())
    return "Yes" if (n + 1) * (m + 1) >= k else "No"

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        return solve()
    finally:
        sys.stdin = old_stdin

# Provided samples
assert run("1 0 0\n") == "Yes", "sample 1"
assert run("2 0 0\n") == "No", "sample 2"
assert run("5 1 2\n") == "Yes", "sample 3"

# Minimum-size input
assert run("1 0 0\n") == "Yes", "one day, no packed clothes"

# Exact boundary: exactly enough combinations
assert run("4 1 1\n") == "Yes", "exactly four outfits are available"

# Just beyond the boundary
assert run("5 1 1\n") == "No", "only four outfits are available"

# Maximum values
assert run("1000000000 1000 1000\n") == "No", "maximum k exceeds all possible outfits"

# Maximum possible number of outfits
assert run("1002001 1000 1000\n") == "Yes", "exact maximum number of outfits"

# One clothing category has no packed items
assert run("3 2 0\n") == "Yes", "three shirts and one pair of jeans give three outfits"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`1 0 0`|`Yes`| 最小输入和已穿服装的贡献|
 |`4 1 1`|`Yes`| 可行性边界上的精确相等 |
 |`5 1 1`|`No`| 一日超越境界，捕捉`>`相对`>=`错误|

 ## 边缘情况

 第一个不明显的情况是`1 0 0`。 计算给出`(0 + 1) * (0 + 1) = 1`，这足够一天的时间，因此算法打印`Yes`。 仅计算包装好的衣服的解决方案会错误地得出没有衣服的结论。 

第二种情况是`2 0 0`。 计算仅给出一种可用的服装，而需要两种不同的服装。 自从`1 < 2`，算法打印`No`。 服装的任何一部分都无法改变。 

等式边界表示为`4 1 1`。 有两件 T 恤和两条牛仔裤，正好有四种组合。 比较的是`4 >= 4`，所以答案是`Yes`。 这会捕获意外需要比几天更多的服装的实现。 

立即不可能的情况`5 1 1`给出相同的四种组合，但需要五天。 比较就变成了`4 >= 5`，这是假的，所以算法打印`No`。 这是与上一个测试自然相差一个的同伴。 

最后，考虑`1002001 1000 1000`。 有`1001 * 1001 = 1002001`可能的服装，与天数完全匹配。 该算法在恒定时间内接受案例，这说明了为什么不需要构建或存储单独的服装组合。
