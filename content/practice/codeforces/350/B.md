 ## 解决方案
 ## 问题理解

 我们给出了一个有向结构`n`代表滑雪胜地的对象。 每个物体要么是一座山，要么是一家酒店。 每个对象至多有一个通向另一个对象的外出滑雪道，而酒店根本没有外出滑雪道。 这意味着每个节点的出度最多为 1，并且所有边都指向“下一个”节点，形成最终终止于酒店的有向链的集合。 

任务是选择一条有效的路径，从某座山开始，沿着出去的滑雪道一步一步直到到达一家酒店为止。 在所有这样的有效链中，我们必须输出访问节点数最长的一条。 

该结构意味着每个节点至多有一个出边，因此从任何起点都有唯一的前向行走。 真正的决定是选择通往最深处的酒店的最佳起点山。 

和`n ≤ 10^5`，任何解都必须是线性或接近线性的。 尝试每个起始节点并模拟行走的二次方法可以降级为`O(n^2)`在一个长链中，这太慢了。 该图实际上是有向链的森林，因此我们应该期待动态编程或记忆化遍历解决方案`O(n)`。 

如果尝试从所有山脉开始而不缓存结果，就会出现一个微妙的问题。 许多起始点可能共享长后缀，并且重复地重新计算它们会导致重复遍历相同的链。 

另一个边缘情况是某些节点可能是孤立的酒店（没有传出边缘也没有传入边缘）。 这些节点形成长度为一的有效路径，并且必须将它们考虑为最大值。 

## 方法

 一个蛮力的想法是将每座山视为起点，沿着其向外的边缘直到到达酒店，沿途计算步数。 这是正确的，因为该图没有向前分支，因此每个起点都定义了一条路径。 然而，在最坏的情况下，该图是一条长度较长的链`n`。 从第一个节点开始遍历`n`节点，从第二个开始遍历`n-1`，依此类推，大致导致`n + (n-1) + ... + 1 = O(n^2)`运营。 

关键的观察是每个节点至多有一个出边，因此该结构是向后合并但从不向前分支的不相交链的集合。 这使得可以使用记忆来计算每个节点以酒店为终点的链的长度。 一旦知道节点的长度，就不需要重新计算。 我们还可以将下一个节点存储在最佳路径中，以便重建变得简单。 

这将问题转化为计算函数图中的最长后缀到酒店的距离，其中传出度≤ 1。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 最优（函数图上的 DP）| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将每个节点建模为最多具有一个传出边缘。 对于每个节点，我们计算通过重复遵循传出边缘直到到达终点酒店而获得的路径长度。 

1. 从数组隐式构建传出邻接关系`a`， 在哪里`a[i]`是下一个节点或零。 这为每个节点提供了一个后继者。 
2. 维护一个记忆数组`dp[v]`存储从以下位置开始的最大路径长度`v`和一个`next[v]`重建的指针。 我们还跟踪节点是否已经计算以避免重新计算。 
3.对于每个节点`v`，如果它已经计算出来，我们就跳过它。 否则，我们通过向前行走来计算其链长度，直到我们到达计算节点或到达没有传出边缘的终端节点。 
4. 一旦我们到达链的末端（酒店或没有传出边缘的节点），我们就为其分配基值`1`因为它本身就形成了一条长度的路径。 
5. 然后我们沿着我们遍历的路径向后传播值，分配`dp[u] = 1 + dp[a[u]]`和设置`next[u] = a[u]`。 这确保每个节点知道其后缀链有多长。 
6.计算完所有dp值后，我们在所有山中选择最大化的起始节点`dp[v]`。 
7. 最后，通过重复遵循来重建路径`next[]`指针直到终止。 

关键的设计选择是在 DP 传播期间存储下一个指针，这使我们能够重建精确的最大链而无需重新计算。 

### 为什么它有效

 每个节点都有唯一的前向路径，因此其dp值仅取决于下一个节点。 这定义了函数依赖。 通过向后解析接收器中的 dp 值，每个节点的值都被固定一次。 由于在记忆过程中每条边最多被处理一次，因此不会出现不一致的状态，并且最终选择的起点必然会产生全局最长的有效链。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    typ = list(map(int, input().split()))
    a = list(map(int, input().split()))

    dp = [0] * (n + 1)
    nxt = [0] * (n + 1)
    vis = [False] * (n + 1)

    sys.setrecursionlimit(10**7)

    def compute(v):
        if vis[v]:
            return dp[v]

        path = []
        cur = v

        while cur != 0 and not vis[cur]:
            path.append(cur)
            cur = a[cur]

        if cur == 0:
            dp[cur] = 0

        for node in reversed(path):
            if a[node] == 0:
                dp[node] = 1
                nxt[node] = 0
            else:
                dp[node] = 1 + dp[a[node]]
                nxt[node] = a[node]
            vis[node] = True

        return dp[v]

    for i in range(1, n + 1):
        if not vis[i]:
            compute(i)

    start = 1
    best = -1
    for i in range(1, n + 1):
        if typ[i - 1] == 0:
            continue
        if dp[i] > best:
            best = dp[i]
            start = i

    path = []
    cur = start
    while cur != 0:
        path.append(cur)
        cur = nxt[cur]

    print(len(path))
    print(*path)

if __name__ == "__main__":
    solve()
```该实现首先使用路径压缩样式遍历为所有节点构建 dp 值。 它不是递归，而是向前迭代，存储链，然后向后分配 dp 值。 这避免了长链上的递归深度问题。 

这`typ`数组仅在选择起点时使用，确保我们从一座山开始。 酒店被排除在外，因为该问题需要首先`k-1`节点是山脉，只有最后一个节点是酒店。 

重建使用`nxt[]`，在 DP 传播期间被填充。 这保证了 O(k) 重建时间。 

## 工作示例

 ### 示例 1

 输入：```
5
0 0 0 0 1
0 1 2 3 4
```我们有一个单链：`1 → 2 → 3 → 4 → 5`，其中 5 是一家酒店。 

| 步骤| 节点| 下一页 | dp 分配 |
 | --- | --- | --- | --- |
 | 建造| 5 | 0 | dp[5]=1 | dp[5]=1 |
 | 建造| 4 | 5 | dp[4]=2 | dp[4]=2
 | 建造| 3 | 4 | dp[3]=3 | dp[3]=3 |
 | 建造| 2 | 3 | dp[2]=4 |
 | 建造| 1 | 2 | dp[1]=5 |

 最好的起始山是节点 1，因为它产生的最大链长度为 5。重建的路径遵循 1 → 2 → 3 → 4 → 5，确认了正确性。 

### 示例 2

 输入：```
4
0 0 1 1
0 3 0 0
```这里我们有两条链：`2 → 3`和`1`是孤立的，并且`3`和`4`是酒店。 

| 步骤| 节点| 下一页 | DP |
 | --- | --- | --- | --- |
 | 建造| 3 | 0 | dp[3]=1 | dp[3]=1 |
 | 建造| 2 | 3 | dp[2]=2 | dp[2]=2
 | 建造| 1 | 0 | dp[1]=1 | dp[1]=1 |
 | 建造| 4 | 0 | dp[4]=1 | dp[4]=1 |

 最好的山是节点 2，产生路径`2 → 3`。 这证实了该算法正确处理多个组件和孤立节点。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 在 DP 传播过程中，每个节点最多被访问和处理一次 |
 | 空间| O(n) | 用于 dp、下一个指针和访问跟踪的数组 |

 线性复杂度完全符合以下约束：`n ≤ 10^5`，内存使用量也是线性的，完全在 256 MB 以内。
