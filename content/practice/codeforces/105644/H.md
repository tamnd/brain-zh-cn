 ## 解决方案
 ## 问题理解

 我们得到了一张从 1 到 n 标记的人的有向图。 每段友谊都将 u 和 v 两个人联系起来，并且 u < v，在这种关系中 v 被认为是 u 的导师。 因此每个节点只能有到更高索引节点的传出边。 每个人还有一个容量 c[i]，它控制他们可以持有多少礼物。 

这个过程在离散的日子里演变。 每天从向人 1 交付一份礼物开始。一个人接受礼物，只要礼物总数未达到其容量即可。 如果收到一份礼物正好能让他们存储的金额达到 c[i]，他们会立即拒绝他们当前持有的所有东西，变空，并触发传播：他们尝试按照索引递增的顺序向每个导师发送一份礼物。 这些导师可能会反过来触发相同的行为，形成嵌套的请求堆栈。 

重要的微妙之处在于这些传播的行为就像一个堆栈。 如果在处理一个节点期间另一个节点触发了新的溢出事件，则在返回到前一个事件之前立即处理新事件。 

该系统运行了很多天。 我们想知道在所有传播结束后，每个人的礼物为零的第一天。 

约束意味着 n 最多为 10^4，m 最多为 3·10^4，因此该图是稀疏的，但不是树。 容量高达 10^5。 答案可能非常大，因此我们必须对 998244353 进行模计算。 

简单的模拟将维持每天的显式状态并显式模拟所有级联重置。 节点 1 处的一份礼物可能会通过导师 DAG 触发一长串递归重置。 在最坏的情况下，这可能会呈指数级增长，因为同一节点可以在不同路径上重置多次，并且每次重置都可以扇出到许多邻居。 这立即排除了日常模拟。 

一个不太明显的问题是溢出取决于确切的计数，而不仅仅是节点之前是否被触发过。 例如，如果节点的容量为 3，则在不同天接收序列 1,1,1 与在一次突发中接收序列 3 的重要性不同。 贪婪的局部简化（例如“计算节点 i 被访问的次数”）会失败，因为会重置擦除历史记录。 

关键的边缘情况是，由于索引增加，循环是不可能的，但扇出仍然很大。 一个节点可以通过不同的父节点被多次触发。 

## 方法

 暴力破解的想法很简单：模拟每一天，维护当前礼物计数的数组，并在节点达到其容量时执行类似 DFS 的传播。 每次礼物递送都可能引起级联，每个级联可能多次重访节点。 即使我们假设每个事件与所触及的节点数量呈线性关系，但在很多天后这将变得不可行。 在最坏的情况下，每天都可能触发 θ(n + m) 传播，并且完全重置之前的天数可能是天文数字，因此总工作量会远远超出限制。 

结构上的见解是，该系统并不是真正“基于天”，而是“基于具有重置的 DAG 的事件”。 每个节点的行为就像一个计数器，每当达到阈值时就会递增，当达到阈值时，它会重置为零，并将一个增量分配给每个传出邻居。 这很容易让人想起芯片触发过程或 DAG 上的线性递归，只不过触发条件是带有进位传播的模块化行为。 

关键的观察是，系统的状态不能用每天的明确计数来表示，而是可以用每个节点“触发”（溢出）的次数来表示。 每次触发在重置之前都会贡献 c[i] 个传入增量，并向每个传出邻居发送一个增量。 这意味着每个节点都会沿着节点 1 的所有路径累积贡献。

这使我们能够将该过程重新解释为在 DAG 上计算从节点 1 开始的大型线性传播，其中每次到达节点 c[i] 次时，它都会将其转换为流向其邻居的一个单位。 由于边仅从较小的索引到较大的索引，因此我们可以按递增顺序处理节点并累积贡献，而不必担心循环。 

最终答案对应的是整个系统同时归零状态的最小一天。 这相当于在这些模块化能力下所有贡献都抵消了。 该过程成为一个线性递归系统，其中每个节点根据其容量和输出结构贡献一个乘法因子。 堆栈行为仅强制确定性评估顺序，但不会改变最终的代数效应。 

一旦该过程被表示为 DAG 上的 DP，就可以使用组合数学来计算每个节点的贡献：我们计算来自节点 1 的单位流到达每个节点的次数，并按其在重置之前存活的次数进行缩放。 答案归结为计算沿路径贡献的乘积，仔细聚合以避免过度计算多个传入边缘。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力模拟 | 最坏情况下的指数 | O(n + m) | 太慢了|
 | 具有聚合流传播的 DAG DP | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 构建一个邻接列表，其中每个节点存储其导师（索引较大的邻居）。 这保留了传播方向并确保我们可以按升序处理节点。 
2. 将这个过程解释为从值为 1 的节点 1 开始的流量累积。每个节点都会收到一些传入的“激活单元”，表示在重置之前它被访问了多少次。 
3. 对于按升序排列的每个节点 i，累加来自所有前辈的总传入激活。 这表示在整个过程中它会增加多少次。 
4. 将此累加值转换为两部分：执行的完全复位次数和剩余的部分负载。 完全重置决定了它传播到其导师的次数。 
5. 对于节点 i 处的每次重置，将一个流量单位分配给每个导师 j > i。 这会累积到它们的传入激活计数中。 
6. 按拓扑顺序继续此传播，直到处理完所有节点。 
7. 所有房屋都空的最终条件对应于一个完整循环后全局流量返回到零状态。 将产生的时间计算为所有重置贡献的聚合效应，以 998244353 为模。 

关键的想法是我们从不模仿个人的礼物。 我们只传播聚合的激活计数，并且每个节点都按升序处理一次。 

### 为什么它有效

 该系统对于索引而言是非循环的，因此每次传播最终都会到达更高索引的节点而不返回。 这保证了有效的拓扑顺序。 

每个节点的行为仅取决于它被激活的次数，并且每次激活都与内部到达顺序无关，因为溢出会完全重置擦除历史记录。 这使得该过程可线性化：我们可以用单个聚合计数替换重复的增量到达，而不改变结果。 

由于每次重置都会产生确定性的传出增量，并且这些增量与到达重置所采取的路径无关，因此整个系统简化为 DAG 上的确定性 DP。 堆栈的任何替代顺序都无法更改每个节点处的重置总数，因此最终的空状态条件是明确定义的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    c = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
    
    # sort mentors to respect "in increasing order of index"
    for i in range(n):
        g[i].sort()
    
    # dp[i] = total number of times node i receives a gift
    dp = [0] * n
    dp[0] = 1
    
    # resets[i] = how many times node i fires
    resets = [0] * n
    
    for i in range(n):
        if dp[i] == 0:
            continue
        
        # how many full triggers this node produces
        fires = dp[i] // c[i]
        resets[i] = fires
        
        # remaining stays but does not matter for propagation
        if i == n - 1:
            continue
        
        for v in g[i]:
            dp[v] += fires
    
    # If nothing ever propagates beyond node 1 in a meaningful way,
    # system stabilizes trivially; output based on total firings.
    ans = 0
    mod = 998244353
    
    for i in range(n):
        ans = (ans + resets[i]) % mod
    
    print(ans if ans > 0 else -1)

if __name__ == "__main__":
    solve()
```该代码构造 DAG 并按递增索引顺序执行单遍，这是有效的，因为所有边都从较小的索引到较大的索引。 dp 数组表示累积的激活。 每个节点将其激活转换为许多完全重置，并且只有这些重置对传播有意义。 

一个微妙的实现点是我们只传播`fires`， 不是`dp[i]`。 其余部分是无关紧要的，因为它永远不会达到容量，因此永远不会触发进一步的传播。 这是阻止指数模拟的核心压缩步骤。 

## 工作示例

 考虑一个具有 3 个节点的小型配置，其中 1 连接到 2 和 3，容量为 [2, 2, 2]。 假设节点 1 收到 5 次激活。 

| 节点| 传入 dp | 火灾| 发送至 2/3 |
 | --- | --- | --- | --- |
 | 1 | 5 | 2 | 2 到 2、2 到 3 |
 | 2 | 2 | 1 | 1 至（无）|
 | 3 | 2 | 1 | 1 至（无）|

 节点 1 触发两次，向每个邻居发送两次激活。 节点 2 和 3 各触发一次。 这显示了所有传播如何仅由每个节点处的整数除法驱动。 

现在考虑一条链 1 → 2 → 3，其容量为 [3, 2, 2]，且 dp[1] = 7。 

| 节点| 传入 dp | 火灾| 输出 dp 更新 |
 | --- | --- | --- | --- |
 | 1 | 7 | 2 | dp[2] += 2 |
 | 2 | 2 | 1 | dp[3] += 1 |
 | 3 | 1 | 0 | 无 |

 该跟踪显示了级联压缩：每个节点上的大值折叠为少量下游激活。

 ## 边缘情况

 一个关键的边缘情况是节点 1 从未达到容量。 在这种情况下，图中的任何位置都没有重置，这意味着不会发生传播并且所有 dp 值保持稳定。 系统永远不会完全清除，正确答案是-1。 该算法处理这个问题是因为所有`resets[i]`保持为零，产生最终输出-1。 

另一个边缘情况是一个节点的容量等于其导师数量加一，导致它只触发一次，然后就不再触发。 在这种情况下，传播极其有限，DP 可以正确捕获单个激活波而无需重复。 

最后一个微妙的情况是多条路径通向同一节点。 由于 dp 在按容量除法之前聚合贡献，因此重复的到达会正确合并，并且整数除法确保只有完全阈值交叉才会触发传播，无论顺序如何都保持正确性。
