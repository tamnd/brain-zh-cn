 ## 解决方案
 ## 问题理解

 给定一个由字符组成的字符串，任务是确定可以由它组成多少个不同的子序列。 删除一些字符而不改变剩余字符的顺序得到子序列。 如果两个子序列至少有一个位置或字符不同，即使它们具有相同的长度，也被认为是不同的。 

考虑这个问题的一个有用方法是，字符串中的每个字符都提供一个二元决策，要么将其放入子序列中，要么跳过它。 然而，这种幼稚的观点严重夸大了，因为重复的字符通过不同的选择模式创建相同的子序列。 目标是仅计算唯一的结果字符串。 

输入只是这一个字符串，因此整个困难在于处理重复并确保不会多次计算重复项。 输出是一个整数，表示不同子序列的数量，根据约定通常包括空子序列。 

约束的影响是直接的。 如果字符串长度达到 10^5 左右，则无法枚举子序列，因为子序列的朴素空间为 2^n。 即使存储它们，早在时间限制之前就已经超出了内存限制。 这迫使采用线性或近线性 DP 方法，其中每个字符都以恒定时间更新处理一次或几次。 

当角色重复时，会出现微妙的失败情况。 

例如，考虑字符串“aa”。 简单的 2^n 推理会产生四个子序列：“”、“a”、“a”、“aa”。 重复的“a”出现两次，但只应计算一个不同的子序列。 简单的位掩码或递归方法会错误地计算两者。 

另一个边缘情况是像“abab”这样的字符串。 许多子序列在不同的索引选择中重复，并且如果没有纠正过度计数的机制，简单计数很快就会偏离正确性。 

## 方法

 蛮力的想法是递归地或通过位掩码生成所有子序列。 对于每个位置，我们要么包含或排除该字符，从而生成 2^n 个子序列。 我们将每个生成的字符串插入到一个集合中以进行重复数据删除。 

这是正确的，因为每个子序列都是显式构造的，并且该集合确保了唯一性。 当 n 增大时，问题立即出现。 当 n = 20 时，我们已经有大约一百万个子序列，这几乎是无法管理的。 当 n = 100000 时，子序列的数量是天文数字，使得这种方法在时间和内存上完全不可行。 

关键的观察是，我们可以逐步构建答案，同时跟踪每个角色贡献了多少个新子序列。 处理新字符时，每个现有子序列都可以忽略它或包含它，从而使计数加倍。 然而，如果该字符之前出现过，我们必须减去由于其先前出现而已经计数的子序列的贡献。 

这导致了经典的重现。 令 dp[i] 为使用直到位置 i 的前缀的不同子序列的数量。 当我们在位置 i 添加一个新字符 c 时，dp[i−1] 中的每个子序列都会产生两个变体，因此我们从 2 * dp[i−1] 开始。 但如果 c 先前出现在位置 j 处，则在 j 之前形成的子序列已经包含了先前的 c，因此我们减去 dp[j−1]。 这可以避免重复计算由于重复字符而最终相同的子序列。 

为了有效地实现这一点，我们维护每个字符的最后出现索引。 这允许对每个步骤进行恒定时间校正。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（生成所有子序列）| O(2^n) | O(2^n) | O(2^n) | O(2^n) | 太慢了|
 | 具有上次出现跟踪功能的 DP | O(n) | O(σ) | 已接受 |

 ## 算法演练

 我们从左到右处理字符串，维护一个动态编程数组和每个字符最后出现位置的记录。 

1. 初始化dp[0] = 1，表示空子序列。 这充当不选择任何字符的基本状态。 
2. 维护一个字典last，存储每个字符最后出现的位置。 
3. 对于从 1 到 n 的每个位置 i，读取字符 c。 
4. 计算 dp[i] = 2 * dp[i−1]。 这说明了在所有先前的子序列中包含或排除新字符。 
5. 如果 c 之前出现在位置 j，则从 dp[i] 中减去 dp[j−1]。 这会删除先前处理 c 时已计算的重复子序列。 
6. 将 i 存储为最后一次出现的 c。 
7. 继续直到字符串末尾。 
8. 最终答案是dp[n]。 

减法步骤是关键的校正。 如果没有它，通过重复字符生成的相同子序列将被多次计数，因为可以使用同一字符的不同出现来形成相同的逻辑子序列。 

### 为什么它有效

 关键不变量是 dp[i] 始终表示使用以 i 结尾的前缀形成的不同子序列的数量。 加倍步骤考虑了扩展先前子序列的所有方式，而减法则确保最后一个字符重复出现的任何子序列不会被多次计数。 每个不同的子序列都与其最后一个字符被选择的最早位置相关联，这保证了唯一的构建路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    MOD = 10**9 + 7

    dp = [0] * (n + 1)
    dp[0] = 1

    last = {}

    for i in range(1, n + 1):
        c = s[i - 1]
        dp[i] = (2 * dp[i - 1]) % MOD

        if c in last:
            j = last[c]
            dp[i] = (dp[i] - dp[j - 1]) % MOD

        last[c] = i

    print(dp[n] % MOD)

if __name__ == "__main__":
    solve()
```执行直接遵循递归。 dp 数组存储每个前缀的计数，最后确保我们可以在每个字符的恒定时间内纠正过度计数。 每一步都应用模运算，以防止溢出并将值保持在界限内。 

一个微妙的实现细节是索引。 dp 数组相对于字符串的索引为 1，因此 dp[i] 对应于 s[:i]。 这使得减法 dp[j−1] 与前缀边界一致。

 ## 边缘情况

 对于像“aaaa”这样的字符串，算法会重复减去之前的贡献。 在每个步骤中，最后一个出现的位置向前移动，确保仅保留每个子序列的最早构造。 

简单追踪一下，dp 演化为 2, 3, 4, 5 → 每次使用 dp[0], dp[1], dp[2] 进行修正，确保最终结果变成 5，对应“”，“a”，“aa”，“aaa”，“aaaa”。 

对于没有重复字符的字符串（例如“abcd”），不会触发减法，因此 dp 在每一步都会加倍。 这证实了当不考虑重复时，递归正确地退化为完整的 2^n 结构。
