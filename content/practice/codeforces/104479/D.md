 ## 解决方案
 ## 问题理解

 我们正在构建一个标记为 1 到 n 的顶点的有向完整图。 对于每一对顶点 u 和 v，在它们之间创建一条有向边。 方向是随机但有偏差的：如果 u 小于 v，则 u 到 v 的边以 a/b 的概率出现，否则边以 1 − a/b 的概率从 v 到 u。 所有配对均独立决定。 

当所有边都固定后，该图就是一场锦标赛。 任务是计算该锦标赛不包含有向循环的概率，这意味着其边形成一致的顶点排序。 

当存在顶点排序使得每条边都按该顺序指向前方时，锦标赛是非循环的。 换句话说，随机方向必然会意外地产生全序。 

约束很大，n 高达 10^6。 这立即排除了 n 中的任何二次方，因为 n^2 对边已经隐式存在。 即使对边进行 O(n^2) 推理也是不可能的，因此解决方案必须将所有对的贡献压缩为封闭形式或可以在线性时间内评估的乘积。 

如果尝试直接模拟或计算排列，就会出现一种微妙的失败情况。 尽管答案是一致概率的所有排列的总和，但枚举排列是阶乘的，并且即使对于超出平凡大小的小 n 也是完全不可行的。 

另一个隐藏的陷阱是将所有锦标赛视为统一的。 当 a = b/2 时，对称性给出已知结果，但这里的偏差取决于固定的标签顺序，因此反转或重命名顶点会以结构化方式而不是均匀地改变概率。 

## 方法

 如果我们首先忽略概率，非循环锦标赛的结构很简单：每个非循环锦标赛恰好对应于顶点的一个总排序。 如果我们修复顶点的排列，则只有一种方法可以使所有边的方向与其一致。 

这提出了一种强力方法：迭代顶点的所有排列，计算随机过程精确产生该方向的概率，并对所有贡献求和。 对于固定排列，每对顶点贡献因子 a/b 或 1 − a/b，具体取决于方向是否与排列顺序匹配。 这是正确的，但立即失败，因为有 n! 排列，这太大了。 

关键的观察结果是，排列的概率仅取决于它相对于自然顺序 1 到 n 的反转次数。 每对 u < v 的贡献不同，具体取决于排列是将 u 保留在 v 之前还是将它们颠倒。 这将排列之和转化为逆计数的经典马洪生成函数。 

众所周知，该物体作为产品的因素非常漂亮：

 (1 + q)(1 + q + q^2)...(1 + q + ... + q^{n−1}),

 其中 q 是从边缘概率导出的比率。 这将指数和分解为线性时间乘积。 

剩下的工作是代数归一化：分解出与概率基数 p 对应的常数项，并将其转换为边数，并将所有内容转换为干净的模块化表达式。

 | 因式分解反演生成函数 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们表示 p = a / b 并考虑每个无序顶点对。 对于每一对，该过程都会独立选择一个方向。

1. 将问题转化为对所有顶点排列求和。 每个排列代表锦标赛的候选拓扑排序。 当锦标赛的边缘与某些排列一致时，它就是非循环的。 
2. 确定排列 σ 并计算其概率。 对于每对顶点 u 和 v，边必须符合 σ 的阶数。 如果 σ 将 u 放在 v 之前，我们需要 u → v； 否则我们需要 v → u。 
3. 观察到，对于标签顺序中 u < v 的一对 (u, v)，贡献仅取决于 σ 是否保留或反转该自然顺序。 如果 σ 将 u 保持在 v 之前，则概率贡献为 p。 如果 σ 反转它们，则贡献为 1 − p。 
4. 计算有多少对相对于自然顺序被 σ 反转。 将此数称为 inv(σ)。 总共有 C = n(n−1)/2 对。 那么 σ 的概率就变为 p^{C − inv(σ)} (1 − p)^{inv(σ)}。 
5. 从每一项中分解出 p^C。 总概率变为 p^C 乘以 ((1 − p)/p)^{inv(σ)} 排列之和。 
6. 引入 q = (1 − p) / p。 剩余的和正是大小为 n 的排列上的逆生成函数。 这是马洪分布和，等于 (1 + q + q^2 + ... + q^{i−1}) 的 i 从 1 到 n 的乘积。 
7. 迭代评估该产品。 保持 q 的幂，以便可以在 O(1) 时间内根据先前的值计算每个因子 (1 + q + ... + q^{i−1})。 
8. 将最终乘积乘以 p^C，并使用模逆除法返回模 998244353 的结果。 

### 为什么它有效

 每个非循环锦标赛恰好对应于一种顶点排列，并且生成固定锦标赛的概率仅取决于相对于自然标记的反转结构。 这将整个问题简化为排列的加权计数，其中权重仅取决于反转数。 由于反演数与 Mahonian 分布的统计量相同，因此总和分解为已知的 q 阶乘积，从而保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

n, a, b = map(int, input().split())

p = a * modinv(b) % MOD
one_minus_p = (b - a) * modinv(b) % MOD

C = n * (n - 1) // 2

# q = (1-p)/p
q = one_minus_p * modinv(p) % MOD

# compute product (1 + q + ... + q^{i-1})
prod = 1
cur_sum = 1   # q^0
cur_pow = 1   # q^0

for i in range(2, n + 1):
    cur_pow = cur_pow * q % MOD
    cur_sum = (cur_sum + cur_pow) % MOD
    prod = prod * cur_sum % MOD

ans = pow(p, C, MOD) * prod % MOD
print(ans)
```代码首先根据边缘偏差构建概率比 q。 然后，它通过迭代维护 q 的幂并累积几何前缀来构造 q 模拟阶乘。 最后，它乘以 p 得到边的总数，这说明了始终选择前向的基本概率贡献。 

一个常见的错误是忘记按 b 进行归一化，这会导致模运算下的缩放不正确。 另一个微妙之处是使用模逆来安全地计算 q，因为在模算术下不可能直接除法。 

## 工作示例

 ### 示例 1

 输入：

 n = 3，a = 1，b = 3

 这里 p = 1/3，因此每个前向边缘出现的可能性小于后向边缘。 

我们计算总共 C = 3 条边。 

比率 q = (1 − p)/p = 2。 

我们打造的产品：

 我=1：1

 我 = 2: 1 + q = 3

 我 = 3: 1 + q + q^2 = 7

 所以乘积 = 3 × 7 = 21。 

现在乘以 p^3 = (1/3)^3 = 1/27。 

最终概率 = 21/27 = 7/9。 

这对应于这样的事实：即使向前方向不太可能，非循环结构在多种排列中仍然是可能的。 

### 示例 2

 输入：

 n = 2，a = 1，b = 2

 有一个边缘。 无论方向如何，它都是非循环的。 

C = 1，p = 1/2，q = 1。 

产品 = (1 + 1) = 2。 

最终结果 = (1/2) × 2 = 1。 

这证实了对于两个顶点，每个结果都是一个 DAG。

 ## 边缘情况

 一种重要的边缘情况是 n = 1 时。没有边缘，因此该图基本上是非循环的。 该算法产生 C = 0，因此 p^C = 1 并且乘积为空，也是 1，给出了正确答案。 

另一个边缘情况是当 a 非常接近 b 时，使得 q 很小。 在这种情况下，q 的幂以域为模很快消失，但运行的几何和保持稳定，因为每一项都是在乘法之前累加的。 

当 a = 1 且 b 较大时，会出现更微妙的情况，从而使 p 非常小。 p^C 的直接求幂必须使用模逆小心地进行，否则除以 b 将会丢失。 该实现在取幂之前显式地在模运算下构造 p，以保持正确性。
