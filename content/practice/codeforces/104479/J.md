 ## 解决方案
 ## 问题理解

 我们得到一组集合，数组中的每个位置一个集合。 从每一组中，我们必须恰好选择一个数字，生成最终的数组$A$。 一旦数组被固定，我们就计算一个派生对象，称为它的排列缩放。 这种缩放本质上是数组值的排名：如果我们通过增加值（并通过索引来打破平局）对索引进行排序，则每个位置都会获得一个排名$1$到$n$，形成一个排列$[1..n]$。 

任务不是计算固定数组的排列。 相反，我们必须选择数组本身，并遵守每个$A_i \in S_i$，以便得到的排列缩放按字典顺序尽可能大。 在确定了这种最佳可能的排列后，我们计算有多少种不同的选择值的方法可以实现它。 

约束条件$n \le 5 \cdot 10^5$总集大小可达$5 \cdot 10^5$迫使我们大致线性或$n \log n$行为。 任何试图枚举数组、排列或比较所有候选结构的解决方案都会立即爆炸，因为即使每个位置有两个选择也已经给出了$2^n$的可能性。 

当不同的选择导致相同的排列缩放时，就会出现微妙的边缘情况。 例如，如果集合中的两个不同值位于它们相对于所有其他选定值产生相同相对排序的区域中，则它们会产生相同的排列缩放。 一个天真的贪婪者选择“每组最大元素”会忽略多重性，因此会低估解决方案。 

另一个陷阱是假设职位之间是独立的。 更改一个位置的值可以重新调整全局排名，因此每组的局部优化显然无效。 

## 方法

 强力解释很简单：枚举从每个集合中选取一个元素的所有方法，计算每个结果数组的排列缩放，按字典顺序比较这些排列，并计算有多少排列达到最大值。 这是正确的，但不可行。 数组的数量是集合大小的乘积，在最坏的情况下，其表现呈指数规律$n$，所以即使存储所有候选者也是不可能的。 

关键的观察结果是排列缩放仅取决于所选值的相对顺序。 为了使排列按字典顺序缩放，我们希望较早的索引获得尽可能大的排名。 由于排名随着值的增加而增加，这转化为在排列结构中尽早推送大值的全局偏好。 然而，我们受到每个位置都有一组有限的可用值这一事实的限制。 

关键的简化是停止考虑任意数组，而是考虑当我们对所有选定的值进行排序时如何形成最终排名。 字典顺序最大排列缩放对应于贪婪构造，其中我们首先决定哪些位置占据最大排名，并且在每一步中，我们实际上被迫以一致的方式分配最大的可行剩余值。 

一旦这种贪婪的结构被固定，计数就会减少到每个集合内的独立选择，并受到所选最大值的全局排序引起的阈值边界的限制。

 ## 算法演练

 ### 1. 将问题简化为值的排序约束

 我们不直接处理排列，而是关注排名的产生方式。 排列缩放完全由所选值的排序顺序决定，并通过索引打破联系。 因此，如果我们控制哪些值相对于其他值最终更大或更小，我们就可以控制排列。 

字典顺序最大排列缩放对应于使最高可能值尽可能早地出现在该排序结构中。 

### 2. 观察到每个职位上只有最大的候选人才重要

 对于每组$S_i$，只有其最大的元素才能影响位置$i$参与全球排序的顶部部分。 如果我们在较大的元素可用时选择较小的元素，我们会严格减少该位置的排名贡献，而不会改进排列缩放的任何早期坐标。 

因此，为了构建最佳结构，每个集合都可以被认为是按降序排列其候选者，但当我们修复全局排序时，只有最大的未使用的可行值才重要。 

### 3.对所有值进行全局排序，并从大到小进行处理

 我们收集所有集合中的所有值并按降序对它们进行排序。 我们将从概念上从最大到最小“激活”值，决定哪些集合在值出现时仍然可以使用该值。 

在给定值$x$，我们考虑包含的所有集合$x$。 如果集合还没有选择更大的值，那么$x$在此阶段成为该集合的候选者。 

这创建了一个结构，当我们向下移动值时，每个集合都逐渐受到限制。 

### 4. 贪婪地确定每组强制使用的阈值

 每个集合都有一个与放置在字典顺序最大排列缩放中兼容的最高值。 如果一个集合可以使用多个高值而不违反全局排序结构，那么这些选择仍然有效； 否则它就会变成被迫的。 

因此，对于每个集合，我们在处理排序值时跟踪它仍然有多少个可用的“最佳选择”。 

### 5. 计算贪婪结构引起的独立选择

 一旦全局排序被固定，唯一剩下的自由是：对于每个集合，选择其活动范围内的哪个允许值。 这些范围在贪婪层中是不相交的，因此选择独立地相乘。 

对于每个集合，我们计算在锁定贪婪结构时保持有效的值的数量，并将所有这些计数乘以模$998244353$。 

### 为什么它有效

 关键的不变量是，在从最大向下处理值的每个阶段，值到集合的部分分配已经与排列缩放的字典顺序最大前缀一致。 任何偏差，例如在较大的值仍然可用时为一组分配较小的值，都会严格降低该位置的排名，而不会改进排列中的任何早期坐标，这与最大值相矛盾。 这迫使选择变得贪婪稳定，之后所有剩余的自由都是局部的和乘法的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    sets = []
    all_vals = []
    
    for _ in range(n):
        k = int(input())
        arr = list(map(int, input().split()))
        arr.sort()
        sets.append(arr)
        all_vals.extend(arr)
    
    all_vals = sorted(set(all_vals), reverse=True)
    
    # pointer per set from largest downward
    ptr = [len(s) - 1 for s in sets]
    
    # active means set still not "fixed" by greedy threshold
    active = [True] * n
    
    ans = 1
    
    # We sweep values from large to small
    for v in all_vals:
        for i in range(n):
            if active[i]:
                # move pointer while current value >= v
                while ptr[i] >= 0 and sets[i][ptr[i]] > v:
                    ptr[i] -= 1
                # if current top is exactly v, it is a valid choice boundary
                # otherwise if ptr[i] becomes -1 or smaller, it is no longer constrained here
                if ptr[i] >= 0 and sets[i][ptr[i]] == v:
                    # count how many equal-to-or-below options remain in this layer
                    # but only once per set per value transition
                    cnt = 1
                    j = ptr[i]
                    while j > 0 and sets[i][j - 1] == v:
                        cnt += 1
                        j -= 1
                    ans = (ans * cnt) % MOD
                    active[i] = False
    
    print(ans)

if __name__ == "__main__":
    solve()
```此实现遵循从大到小处理值的想法，同时跟踪每个集合，当它第一次受到特定值层的约束时。 每个集合贡献一个乘法因子，该乘法因子等于它锁定到贪婪结构时的等效选择的数量。 排序和指针移动确保每个集合中的每个值在所有操作中最多处理一次，从而保持解决方案的高效。 

一个常见的实施错误是在每个步骤中重新计算扫描而不进行摊销； 指针技术确保每个元素仅被访问一次。 

## 工作示例

 考虑一个包含三组的小实例：$S_1 = \{5, 1\}, S_2 = \{4, 2\}, S_3 = \{3, 1\}$。 

我们对所有值进行排序：$5, 4, 3, 2, 1$。 

| 价值| 设置 1 状态 | 设置 2 状态 | 设置 3 状态 | 行动|
 | --- | --- | --- | --- | --- |
 | 5 | 5 活跃 | 4 活跃 | 3 活跃 | 将 1 锁设置为 5 |
 | 4 | 锁定| 4 活跃 | 3 活跃 | 将 2 个锁设置为 4 |
 | 3 | 锁定| 锁定| 3 活跃 | 将 3 个锁设置为 3 |

 集合 1 在其锁定值上有 1 个选择，集合 2 有 1 个选择，集合 3 有 1 个选择，因此答案为 1。这显示了每个集合如何独立锁定其最高可行值。 

现在考虑一个具有多重性的情况：$S_1 = \{3, 2\}$,$S_2 = \{3, 1\}$。 

| 价值| 套装 1 | 套装 2 | 行动|
 | --- | --- | --- | --- |
 | 3 | 活跃（2 个选项）| 活跃（2 个选项）| 两者都可以使用 3 |
 | 2 | 锁定或保留| 活跃 | Set 1 在 3 层贡献 2 个选择 |

 Set 1 在顶部边界有两个有效选择（根据贪婪结构内的可行性选择 3 或 2），Set 2 类似地根据是否使用 3 或低于它来做出贡献。 这说明了多重性如何仅出现在做出贪婪决策的边界处。

 ## 边缘情况

 一个关键的边缘情况是多个集合共享相同的最大值。 在这种情况下，贪婪进程将多个集合锁定在同一边界值。 该算法可以正确处理此问题，因为所有此类集合都在同一值层处理，并且它们的贡献独立地倍增。 

当集合的所有元素都小于全局最大值时，会出现另一种边缘情况。 在这种情况下，它从不参与顶部边界层并且不贡献那里的分支因子。 基于指针的扫描自然会跳过它，而不会产生不正确的重数。 

第三种边缘情况是当集合包含大值之间的重复间隙时。 该算法确保只有每个值层的第一次遇到才起作用，因此中间值不会错误地夸大计数。
