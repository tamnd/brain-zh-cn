 ## 解决方案
 ## 问题理解

 我们给出了一个排列$p$的数字$1$通过$n$。 我们想要构建另一个排列$q$使用相同的数字，以便每个位置都会发生变化。 对于每个索引$i$，放入的值$q_i$必须不同于$p_i$。 

在所有这些有效排列中，我们必须输出字典顺序最小的排列。 如果不存在有效排列，我们输出$-1$。 

限制非常小。 所有的总和$n$值最多是$1000$。 这意味着即使是$O(n^2)$算法很容易足够快。 不需要复杂的数据结构或高级优化。 真正的挑战是找到字典顺序上最小的有效排列，同时避免固定点。 

最危险的边缘情况出现在施工接近尾声时。 

考虑：```
n = 1
p = [1]
```长度为一的排列只有一种。 任何候选人都会将$1$在位置$1$，创建一个固定点。 正确答案是：```
-1
```总是选择最小可用值的贪心算法会错误地产生$[1]$。 

另一个棘手的情况是：```
p = [1, 2, 3]
```如果我们贪婪地选择不等于当前位置值的最小可用值，我们会得到：```
q = [2, 1, ?]
```仅有的$3$仍然存在，但是$q_3 = 3$是被禁止的。 即使答案有效，粗心的贪婪方法也会陷入困境```
[2, 3, 1]
```存在。 

当仅剩下一个值并且它等于最后一个位置的禁止值时，会发生第三种重要情况。 例如：```
p = [2, 3, 1, 4]
```一个简单的构造可能会达到：```
q = [1, 2, 4, ?]
```仅与$4$其余的。 自从$p_4=4$，放置它会违反要求。 正确的解决方法是将最后选择的值与剩余值交换，产生：```
[1, 2, 4, 3]
```这是有效的并且按字典顺序是最小的。 

## 方法

 蛮力的想法很简单。 生成每个排列$1$通过$n$，检查它是否不同于$p$在每个位置，并保留字典顺序上最小的有效位置。 

这是有效的，因为神秘排列的定义很容易验证。 不幸的是，排列的数量是$n!$。 即使是为了$n=10$，这已经超过三百万种可能性了。 阶乘增长使得蛮力无法使用。 

关键的观察是，词典编纂的极简性表明了贪婪的结构。 决定位置时$i$，我们应该放置不会立即违反条件的最小可用数字$q_i \ne p_i$。 

大多数职位都可以这样处理。 唯一的麻烦出现在最后。 贪婪地填完第一个之后$n-1$位置，可能保留一个值。 如果该值不等于$p_n$，我们只需放置它。 

如果剩余值等于$p_n$，我们必须修复建筑。 由于剩余的值还没有被使用，它一定已经出现在某个较早的位置了$p$。 将其与放置在前一个位置的值交换会删除固定点，同时保留字典最小性。 

这一观察结果将问题转化为一个简单的贪心算法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n! \cdot n)$|$O(n)$| 太慢了 |
 | 最优贪心 |$O(n^2)$|$O(n)$| 已接受 |

 ## 算法演练

 1.如果$n=1$， 输出$-1$。 不存在神秘的排列。 
2. 维护未使用的号码集。 
3. 从左到右处理位置，最后一个位置除外。 
4. 职位要求$i$，选择不等于的最小未使用数字$p_i$。 
5. 从未使用的集合中删除该数字并将其附加到答案中。 
6. 填写第一个后$n-1$位置，只剩下一个数字。 
7. 如果剩余数量与$p_n$，将其放在最后一个位置。 
8. 否则，将其暂时放置在最后位置并交换构造排列的最后两个元素。 
9. 输出排列结果。 

最终交换起作用的原因很简单。 剩下的数等于$p_n$，所以它不能停留在最后一个位置。 前一个位置包含一些不同的值。 交换这两个值会删除末尾的固定点，并且不会创建新的固定点。 

### 为什么它有效

 贪婪选择始终是最优的，因为字典顺序是由两个排列不同的最早位置决定的。 在位置$i$，选择最小的可用有效数字会在所有有效解决方案中产生最小的可能前缀。 

贪婪过程唯一遇到困难的时候是当最终位置仍有一个禁止值时。 在这种情况下，每个早期的选择在字典上都已经是最小的了。 交换最后两个位置会尽可能晚地改变排列，保留最小的前缀，从而保留词典编纂的最小性。 

因此，只要存在一个有效的神秘排列，该算法总是构造一个有效的排列，并且在所有有效排列中，它按字典顺序是最小的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    p = list(map(int, input().split()))

    if n == 1:
        print(-1)
        continue

    unused = set(range(1, n + 1))
    q = []

    for i in range(n - 1):
        for x in range(1, n + 1):
            if x in unused and x != p[i]:
                q.append(x)
                unused.remove(x)
                break

    last = next(iter(unused))
    q.append(last)

    if q[-1] == p[-1]:
        q[-1], q[-2] = q[-2], q[-1]

    print(*q)
```该算法显式地维护未使用的值。 自从$n\le1000$，扫描所有数字$1$到$n$每一步都是完全可以接受的。 

第一个$n-1$职位被贪婪地填补。 在每一步中，与禁止值不同的最小可用数$p_i$被选中。 

附加最后的剩余值。 如果它在最终位置创建固定点，则交换最后两个元素。 

最重要的实现细节是只有在所有职位都被填补后才执行交换。 试图尽早处理这种情况会使逻辑变得复杂并且没有必要。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(n^2)$| 对于每个位置，我们可以扫描来自的所有值$1$到$n$|
 | 空间|$O(n)$| 答案和最多未使用的设置存储$n$价值观 |

 由于总和为$n$所有测试用例最多$1000$， 一个$O(n^2)$解决方案最多执行大约一百万个基本操作，这很容易在限制之内。 

## 测试用例```python
import sys, io

def solve():
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        if n == 1:
            out.append("-1")
            continue

        unused = set(range(1, n + 1))
        q = []

        for i in range(n - 1):
            for x in range(1, n + 1):
                if x in unused and x != p[i]:
                    q.append(x)
                    unused.remove(x)
                    break

        q.append(next(iter(unused)))

        if q[-1] == p[-1]:
            q[-1], q[-2] = q[-2], q[-1]

        out.append(" ".join(map(str, q)))

    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

assert run("4\n3\n1 2 3\n5\n2 3 4 5 1\n4\n2 3 1 4\n1\n1\n") == \
       "2 3 1\n1 2 3 4 5\n1 2 4 3\n-1"

assert run("1\n1\n1\n") == "-1"

assert run("1\n2\n1 2\n") == "2 1"

assert run("1\n3\n2 1 3\n") == "1 3 2"

assert run("1\n4\n1 2 3 4\n") == "2 3 4 1"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |$n=1$|$-1$| 不可能的情况 |

 ## 边缘情况

 考虑：```
1
1
1
```长度为一的排列只有一种。 任何候选人名额$1$在唯一的位置，创建一个固定点。 该算法立即检测到$n=1$和输出$-1$。 

考虑：```
1
3
1 2 3
```贪婪的选择会产生：```
[2,1,3]
```最终值等于禁止值$3$。 该算法交换最后两个位置并获得：```
[2,3,1]
```每个位置都与原始排列不同。 

考虑：```
1
2
2 1
```贪心过程选择：```
[1,2]
```这两个位置都与原始排列不同，不需要修复。 这证实了该算法正确处理最小可解尺寸。 

考虑：```
1
4
2 3 1 4
```最后一步的剩余值为$3$，不等于$4$。 该算法只是将其附加并返回：```
[1,2,4,3]
```这验证了仅在必要时才应用修复步骤。
