 ## 解决方案
 ## 问题理解

 我们得到一个字符串，其中每个位置都有一个小写字母。 唯一允许的移动选择一个字母，找到当前包含该字母的所有位置，并将所有位置按循环顺序递增到下一个字母，这意味着`a → b → ... → z → a`。 该移动的价格仅取决于移动时字符串中所选字母的最左和最右位置。 

任务是转换整个字符串，以便每个位置都以相同的最终字母结束，并且我们希望所有有效操作序列的总成本尽可能最小。 

重要的细节是，操作同时作用于所有出现的字母，因此字母的行为就像移动的位置“组”，随着它们在字母表中前进而逐渐合并。 

这些约束允许字符串最多为 200,000 个字符，这会立即排除任何重复模拟每个步骤的操作并每次扫描字符串的解决方案。 即使对字符串进行 26 次传递也可以，但是每次操作重复重建状态的任何操作都会太慢。 

当事件相距很远时，就会出现微妙的边缘情况。 例如，如果一个字母出现在位置 1 和 n，则其第一次操作的成本已为 n − 1。假设操作是“本地”的或每个字符独立的简单方法将错过这种全局跨度效应。 

另一个边缘情况是字母合并时。 认为`a`发生在位置 1 和 100，而`b`发生在位置 50。转换后`a → b`，新的`b`组跨越位置 1、50 和 100，以取决于历史而不仅仅是初始结构的方式改变未来成本。 

## 方法

 一个蛮力的想法是模拟这个过程。 我们重复选择一个字母，更新所有出现的字母，并通过扫描字符串重新计算成本。 每个操作最多可以触及 O(n) 个位置，并且在最坏的情况下最多可以有 O(26n) 个操作，因为每个字符可能会在字母表循环中经历许多状态。 这会导致大约 O(n²) 的行为，这对于 200,000 个字符来说太慢了。 

关键的见解是扭转观点。 不要考虑任意的​​操作序列，而是确定最终的目标字母。 所有其他字母最终都必须沿着字母表“向前推进”，直到它成为目标。 这意味着对于选定的目标，操作顺序实际上是由字母的循环顺序决定的。 

现在考虑以循环顺序处理目标的字母。 在每一步中，我们采用一个字母类别并将当前属于该字母类别的所有位置合并到下一类别中。 该步骤的成本仅取决于已合并到当前类别的所有位置中的最小和最大索引。 

这将问题转变为维持不断增长的位置集联合并跟踪全局范围。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n²) | O(n) | 太慢了 |
 | 具有间隔合并的循环 DP | O(26n) | O(26n) | O(n) | 已接受 |

 ## 算法演练

 我们尝试将每个字母作为最终目标，并计算将所有内容转换为它的最低成本。 

1. 修复目标字母`T`。 我们将模拟所有字母逐渐转化为`T`沿着循环顺序。 
2. 构建 26 个列表，其中每个列表存储给定字母当前在原始字符串中出现的索引。 这些集合在内部永远不会改变； 相反，它们会合并成更高的字母。 
3. 从前一封信开始`T`循环往复，直至到达`T`。 对于每个字母`c`，我们将此视为一个操作阶段，其中所有发生的`c`被转化为`next(c)`。 
4. 维持一组全局活跃头寸，最初为空。 还保持活动元素之间的当前最小和最大位置。 
5. 处理信件时`c`，我们添加所有位置`c`进入活动集。 合并后，我们使用这些位置更新全局最小值和最大值。 
6. 这一步的成本为`max_position − min_position`，添加到该目标的总成本中。 
7.处理完循环中的所有26个字母后，我们得到目标的总成本`T`。 
8. 对所有 26 个可能的目标重复此操作，并取最小值。 

关键思想是，每个阶段精确对应于最优流程中的一个实际操作，并且成本仅取决于已合并到该阶段的所有位置的跨度。 

### 为什么它有效

 在固定目标流程中的任何时刻，每个位置都恰好属于循环中的一个“当前字母类别”。 随着我们的进步，班级只会向上合并，而不会分裂。 因此，一个类的活动位置集合始终是一些首字母组的并集。 该类别的操作成本仅取决于该联合中的极值索引，因此跟踪全局最小值和最大值就足够了。 由于每个目标每个字母都会被处理一次，因此没有有效的转换序列可以避免这些合并或改变它们的成本贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    pos = [[] for _ in range(26)]
    for i, ch in enumerate(s):
        pos[ord(ch) - 97].append(i)

    INF = 10**18
    ans = INF

    for target in range(26):
        active_min = INF
        active_max = -INF
        active = False
        total = 0

        # process letters in cyclic order ending at target
        for step in range(1, 27):
            c = (target - step) % 26

            if pos[c]:
                active = True
                for p in pos[c]:
                    if p < active_min:
                        active_min = p
                    if p > active_max:
                        active_max = p

            if active:
                total += active_max - active_min

        ans = min(ans, total)

    print(ans)

if __name__ == "__main__":
    solve()
```该实现预先计算每个字母的位置，然后针对每个候选目标模拟循环合并过程。 内循环遍历 26 个字母，当每个目标的字母被激活时，每个位置都会被考虑一次。 运行最小值和最大值定义了每个操作阶段的成本。 

一个常见的陷阱是通过每次扫描所有活动位置来重新计算最小值和最大值，这会将复杂性提高到 O(n²)。 保持增量最小值和最大值可以完全避免这种情况。 

另一个微妙之处是正确的循环排序。 循环必须从目标之前的字母开始并向前进行，否则合并的集合将无法反映正确的转换顺序。

 ## 边缘情况

 对于像这样的单字符字符串`a`，算法初始化没有有意义的区间。 由于没有合并会产生价差，因此每个目标都会立即产生零累积成本，并且最小值正确返回零。 

对于像这样的字符串`az`，选择任何目标都会导致最多一个合并步骤，其中一次有一个位置处于活动状态。 最小值和最大值始终保持相等，因此跨度成本始终为零，符合孤立字母永远不会产生间隔增长的直觉。 

对于高度交替的图案，例如`ababab`，当两个字母在给定目标下激活时，位置会逐渐合并到更大的连续范围中。 该算法正确地累积了不断增加的跨度，因为一旦模式的两侧进入相同的活动类，最小值和最大值就会扩展。
