 ## 解决方案
 ## 问题理解

 我们得到了一个逐行构建的三角形数字表。 顶部单元格和两个外边框都固定为零。 每个其他单元格的定义方式是取其正上方的两个单元格（左上方和右上方）并计算它们值的 MEX。 集合的 MEX 是集合中未出现的最小非负整数。 

每个测试用例都要求这个无限结构内的特定位置：第 n 行、第 m 列中的值。 

该约束允许最多 100,000 个查询，n 和 m 都最大为 1e9。 任何尝试显式模拟行的解决方案都是立即不可能的，因为即使计算最多 n 的单行，在最坏的情况下也会花费 O(n^2) 次操作。 预期的解决方案必须在少量推理后将每个查询时间减少到 O(1) 或 O(log n) 时间。 

幼稚的方法也会遇到概念上的陷阱：MEX 不是线性的，因此很容易认为三角形以复杂的方式演化。 然而，该结构稳定为仅依赖于模 2 的二项式系数的简单组合模式。 

一个微妙的边缘情况是小行。 例如，前几行是强制的，有助于锚定直觉：

 第 1 行：0

 第 2 行：0 0

 第 3 行：0 1 0

 第 4 行：0 1 1 0

 第 5 行：0 1 2 1 0

 简单的 MEX 模拟可能会表明稍后会出现更奇特的行为，但实际上值永远不会超过小整数，并且完全由二进制结构决定。 

## 方法

 暴力构造逐行构建三角形。 对于每个单元格，我们计算其上方两个值的 MEX。 计算两个数字的 MEX 是常数时间，因此第 n 行的总工作量为 O(n^2)。 当 n 达到 1e9 时，即使构建超出小限制的前几行也是不可能的。 如果存储的话，计算量也会在内存中呈二次方增长。 

关键的观察结果是，两个值上的 MEX 的行为类似于对该对是 (0,0)、(0,1)、(1,0) 还是包含更大值的紧凑编码。 如果我们只追踪一个值是零还是非零，这个结构就已经类似于帕斯卡的模 2 三角形。一旦我们细化观察，我们发现这个三角形正是 Sierpiński 模式：每个条目对应于某个二项式系数是否为奇数，然后实际数值等于二进制加法中连续进位的数量，这简化为组合表达式除以 2 的最高幂的指数。 

更直接、更清晰的表征出现了：(n, m)处的值等于(m-1)和(n-m)以二进制相加时的进位数，相当于二项式系数C(n-1, m-1)中2的指数。 这是一个众所周知的恒等式：C(a, b) 中 2 的指数等于二进制中 b 和 a-b 相加时的进位数。 

因此，问题简化为计算二项式系数的 2-adic 估值。 

我们使用基于二进制数字和的标准公式来计算它：

 v2(C(a, b)) = popcount(b) + popcount(a-b) - popcount(a)。 

这里 a = n-1 且 b = m-1。 

这为每个查询提供了 O(1) 解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每次测试 O(n²) | O(1) 或 O(n²) | 太慢了|
 | 最佳| 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将每个查询转换为二项式系数的计算。

1. 转换坐标，以便我们使用 a = n-1 和 b = m-1。 这会将三角形索引与从零开始的标准组合索引对齐。 
2. 计算 popcount(a)、popcount(b) 和 popcount(a-b) 的值。 这些表示每个数字的二进制表示形式中设置的位数。 
3. 使用恒等式 v2(C(a, b)) = popcount(b) + popcount(a-b) - popcount(a)。 这直接给出了 2 除二项式系数的次数。 
4. 输出该值作为单元格的答案。 

关键的推理步骤是基于 MEX 的三角形编码二进制进位结构，并且进位恰好对应于二项式系数中的 2 的幂。 

### 为什么它有效

 每个单元仅取决于其父单元中是否出现 0、1 或 2。 此限制可防止值任意增长并强制系统进入二元状态传播。 这种传播与帕斯卡的三角模二幂相匹配。 当二进制加法产生进位时，重复 MEX 的深度就会增加，这是通过二项式系数的 2-adic 估值精确测量的。 由于估值是由 popcount 关系唯一确定的，因此该公式会为每个单元格生成准确的值，而无需模拟三角形。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = n - 1
        b = m - 1

        # v2(C(a, b)) = popcount(b) + popcount(a-b) - popcount(a)
        ab = a - b

        ans = b.bit_count() + ab.bit_count() - a.bit_count()
        print(ans)

if __name__ == "__main__":
    solve()
```实现直接应用导出公式。 减法 a - b 是安全的，因为 m ≤ n 保证 b ≤ a。 为了清晰和高效，使用内置的 bit_count()，每个数字的时间复杂度为 O(1)。 

一个常见的错误是差一索引。 三角形在语句中索引为 1，但组合恒等式假定索引为 0，因此两个坐标在计算前都会移位。

 ## 边缘情况

 n 或 m 等于 1 的左上角区域始终映射到 a = 0 或 b = 0。在这种情况下，公式会简化为 v2(C(a, 0)) = 0，因为 C(a, 0) = 1。实现会正确处理此问题，因为 bit_count(0) 为零，并且减法始终为零。 

当 m 等于 n 时，我们有 b = a 且 a - b = 0。表达式变为 popcount(a) + 0 - popcount(a) = 0，与三角形右边界始终为零的事实相匹配。 

像 n = m = 1e9 这样的大值不会导致溢出或性能问题，因为计算仅依赖于 32 位或 64 位整数的位运算，并且 Python 可以有效地处理它们。
