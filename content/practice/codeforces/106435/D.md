 ## 解决方案
 ## 问题理解

 我们有一排从左到右索引的房间。 特殊的地位`k`发挥着核心作用。 在某些日子里，会发生“主管事件”，每个此类事件都会触发哪些房间参与晨练的时间相关模式。 

当天导演来访后`d`，大家都参与。 从第二天开始，参与度围绕房间对称缩小`k`。 当天`d + y`，停止参与的房间集合形成一个以`k`，每天向每个方向扩展一个房间。 同样，房间距离越远`k`，在最后一次主管访问后，它继续参与的时间越长，最终它会永久退出，直到下一次主管访问重置系统。 

至关重要的是，几天内会有多次董事拜访`d1 < d2 < ... < dq`。 每次访问都会重置流程。 在连续两次访问之间，参与的“衰减”仅取决于最近的访问。 上次访问后，同样的衰退将永远持续下去，直到每个房间最终停止参与。 

任务是计算每个房间在整个时间线上总共参与了多少天。 

约束条件很大：最多`3 · 10^5`房间和导演活动，而天数本身可以长达`10^12`。 这立即排除了几天内的任何模拟。 任何解决方案都必须避免日复一日的迭代，而是将每个导演事件的影响压缩为总贡献。 

上次主管访问后出现了一个微妙的边缘情况。 这个过程并没有就此停止； 相反，收缩会持续进行，直到所有房间都被排除。 假设有限的结束日期或尝试向前模拟直到稳定的天真的方法要么会错过贡献，要么变得不可行。 

另一个常见的陷阱是独立对待每一天。 该状态仅取决于最近的主管访问，而不是所有先前的访问，因此重叠的简单模拟会错误地重复计算或需要禁止性的重新计算。 

## 方法

 直接模拟将根据主管上次访问每天跟踪哪些房间处于活动状态。 每个导演事件可能需要更新所有未来的日子直到下一个事件，并且对于每一天，重新计算活动范围。 这导致大约`O(n * max_gap)`或者更糟，在给定的约束下会崩溃，因为两者`n`而且活动数量很多，日间差距可能很大。 

关键的观察结果是，每个董事事件独立地围绕职位贡献了一个结构化的、对称的“生命周期”模式`k`，这种模式仅取决于距离`k`以及与下一个事件的时间间隔。 我们不考虑天数，而是颠倒视角：对于固定房间，其行为完全由其距离决定`d = |i - k|`。 For each director interval`[di, di+1)`，对房间的贡献仅取决于`d`和间隔长度`L = di+1 - di`。 

每个区间贡献一个函数`d`形式的`min(L, d + 1)`。 这是分段线性的：小距离线性增长，大距离饱和。 这种结构正是使我们能够将问题转化为范围更新的原因`d`。 

我们不是在每个时间间隔迭代房间，而是将`d`作为主轴，并使用线性和常数分量的差分数组来累积所有间隔上的贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（模拟每天的天数或房间数）| O(n·最大间隙) | O(n) | 太慢了|
 | 具有范围更新的间隔到距离分解 | O((n + q) log n) 或 O(n + q) | O(n) | 已接受 |

 ## 算法演练

 ### 最佳想法：研究距离`k`1. 转换每个房间索引`i`到远方`d = |i - k|`。 相同距离的房间表现相同，因此我们只需要计算距离的答案`0 ... max(n)`然后将它们镜像回两侧`k`。 
2. 对于每一连续的董事日`(di, di+1)`，定义区间长度`L = di+1 - di`。 对于最后一个主管日，将间隔视为无界； 实际上它的行为就像`L`是无限的，但是贡献自然还是有上限的。 
3.修复单个间隔和单个距离`d`。 此间隔贡献的活跃天数是两个范围之间的重叠：

 间隔`[di, di+L-1]`和活动窗口`[di, di+d]`。 

该重叠大小简化为`min(L, d+1)`。 

这是关键的简化：复杂的时间过程变成了简单的距离函数。 
4.现在重写`min(L, d+1)`以一种可以有效聚合所有内容的形式`d`：

为了`d < L`，贡献是`d + 1`，并且对于`d >= L`，贡献是`L`。 

因此每个区间都会产生一个线性函数，直到`L-1`然后平坦。 
5. 不要单独应用这个`d`，维持两个远距离数组：

 一个跟踪我们添加斜率的次数`1`从每个区间开始，

 另一个跟踪恒定的偏移量。 

对于每个间隔：

 我们添加一个线性函数`(d + 1)`超过`[0, L-1]`，和一个常数`L`超过`[L, max_distance]`。 

这可以使用差异数组来实现：

 范围添加`+1`坡度和`+1`拦截于`[0, L-1]`,

 和常数的范围添加`L`在`[L, n]`。 
6. 处理完所有区间后，重建每个距离的最终值`d`作为：`answer[d] = d * slope_sum[d] + const_sum[d]`。 
7. 最后，绘制每个房间的地图`i`回到它的距离`d = |i - k|`和输出`answer[d]`。 

### 为什么它有效

 每个房间的参与完全取决于其与房间的距离`k`以及每位董事间隔的独立贡献。 每个区间都贡献相加，贡献函数仅取决于`d`以单调分段线性方式。 因为我们将所有区间效应转换为范围更新`d`，我们保留精确的每个房间总计，同时避免每个房间每个时间间隔的计算。 聚合的线性保证了组合所有间隔时的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q, k = map(int, input().split())
    d = list(map(int, input().split()))
    
    # convert to 0-based for convenience in distance handling
    k -= 1
    
    # we work with distances 0..n-1
    max_d = max(k, n - 1 - k)
    
    # difference arrays for slope and constant
    slope = [0] * (n + 5)
    const = [0] * (n + 5)
    
    # helper to apply range add on slope/const
    def add(l, r, s_val, c_val):
        if l > r:
            return
        slope[l] += s_val
        slope[r + 1] -= s_val
        const[l] += c_val
        const[r + 1] -= c_val
    
    # process intervals
    for i in range(q):
        start = d[i]
        if i + 1 < q:
            L = d[i + 1] - d[i]
        else:
            L = 10**18  # effectively infinite
        
        # we only care up to distance n
        # piecewise:
        # d in [0, L-1]: add (d+1)
        # d >= L: add L
        
        r1 = min(n - 1, L - 1)
        if r1 >= 0:
            # add (d + 1) on [0, r1]
            # slope +1, const +1
            add(0, r1, 1, 1)
        
        if L <= n - 1:
            # add constant L on [L, n-1]
            add(L, n - 1, 0, L)
    
    # build prefix sums
    for i in range(1, n):
        slope[i] += slope[i - 1]
        const[i] += const[i - 1]
    
    # compute answers by distance
    ans = [0] * n
    for i in range(n):
        d_i = abs(i - k)
        ans[i] = slope[d_i] * d_i + const[d_i]
    
    print(*ans)

if __name__ == "__main__":
    solve()
```该实现将每个间隔分为两个结构贡献：线性段和平坦段。 差异数组技巧用于在每个间隔的 O(1) 时间内应用这两种效果。 前缀求和后，各距离`d`可以在常数时间内直接求值。 

一个微妙的点是处理最后一个间隔，即没有下一次导演访问。 我们将其长度视为实际上无限，因此只有线性到饱和的过渡才重要； 在实践中，我们将其上限设置为足够大的值，因为该函数在`d + 1`。 

另一个重要的细节是将房间映射到距离`k`。 这种对称性使得整个还原成为可能。 如果没有它，问题在位置和时间上仍然是二维的。 

## 工作示例

 ### 示例 1

 输入：```
4 2 2
3 5
```我们有`k = 2`（从 0 开始的索引 1）。 距离为：

 | 房间| 索引 | 距离 |
 | --- | --- | --- |
 | 1 | 0 | 1 |
 | 2 | 1 | 0 |
 | 3 | 2 | 1 |
 | 4 | 3 | 2 |

 第一个间隔是`[3, 5)`，所以长度`L = 2`。 第二个是无限的。 

为了`L = 2`，每距离的贡献是`min(2, d+1)`：

 - d=0 → 1
 - d=1 → 2
 - d≥2 → 2

 第二个间隔贡献：

 - d=0 → 1
 - d=1 → 2
 - d=2 → 3

 对两个区间求和：

 | d | 间隔 1 | 间隔 2 | 总计 |
 | --- | --- | --- | --- |
 | 0 | 1 | 1 | 2 |
 | 1 | 2 | 2 | 4 |
 | 2 | 2 | 3 | 5 |

 映射回：

 - 房间 2 得到 2
 - 房间 1 和 3 得到 4
 - 4号房间得到5号

 输出匹配：```
4 2 4 5
```### 示例 2

 输入：```

1 2 5 10 20
```这里`k = 5`（从 0 开始 4）。 距离：

 靠近中心的房间贡献更多的天数，并且每个间隔根据其长度分段增加贡献。 

关键的观察结果是每个间隙都定义了一个饱和阈值，而不是手动扩展所有间隔。 早期的间隔主要贡献线性增长，而后来的长间隔使远处房间的贡献饱和。

 ## 边缘情况

 一种极端情况是只有一位董事来访。 在这种情况下，不会重置，并且衰减会继续，直到每个房间都停止参与。 该算法通过将最后一个间隔视为无界来处理此问题，这会自动生成正确的有限贡献`d + 1`对于每个距离。 

另一种极端情况是房间正好位于某个位置`k`。 它的距离为零，因此每个间隔的贡献始终为`min(L, 1)`，这意味着无论间隙大小，它每个时间间隔都会参与一天。 基于距离的公式自然地捕获了这一点，无需特殊的外壳。 

当董事拜访之间的间隔非常大时，就会出现最后一个微妙的情况。 简单的模拟会尝试迭代这些间隙，但距离公式确保一旦`L`超过`n`，所有贡献立即饱和，并且不会发生额外的结构变化。
