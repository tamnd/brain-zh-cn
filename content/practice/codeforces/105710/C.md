 ## 解决方案
 ## 问题理解

 我们有一组鸟，每只鸟从一条线上的某个水平位置开始，垂直向上飞到最高高度，然后直接下降到同一地面。 复杂的是，风层存在于特定的高度。 每当一只鸟穿过这些风层之一时，它的水平位置就会移动固定的量。 这种转变在上升和下降时都会发生，因此两次穿越同一层的鸟会受到两次影响，而恰好在该高度达到峰值的鸟只会受到一次影响。 

任务是在计算每只鸟在飞行过程中经历的所有风层后计算其最终着陆位置。 

输入大小高达 100,000 只鸟和 100,000 个风层，因此任何独立处理每个风层的每只鸟的解决方案都会太慢。 在最坏的情况下，简单的模拟需要大约 10^10 次操作，这在 1 秒的时间限制下是不可行的。 这立即排除了对所有风层进行每只鸟的扫描。 

一个微妙的问题是，只有当风层位于或低于鸟类的最大高度时，风层才重要。 鸟不会与其峰值以上的任何层相互作用。 这会产生对高度过滤的依赖，而幼稚的实现可能会处理不当。 

一个常见的错误是将所有风层视为对所有鸟类的影响相同。 例如，如果一只鸟的高度为 2，并且高度为 10 处有风层，则应该没有效果。 粗心的解决方案只是简单地聚合所有风而不检查高度，会产生不正确的结果。 

当多个风层共享相同高度时，会出现另一种失败情况。 例如，如果高度 5 处存在两股急流，偏移为 +2 和 -1，则净效应取决于是否同时应用两者或其中一个会覆盖另一个。 正确的处理需要将所有贡献汇总到同一高度。 

最后，高度相同但起始位置不同的鸟必须独立处理，即使它们共享同一组适用的风层。 试图从头开始重新计算每只鸟的风效应的解决方案可能会不必要地重复相同的工作。 

## 方法

 暴力方法独立处理每只鸟。 对于一只鸟，我们将迭代所有风层，检查层高度是否小于或等于鸟的峰值高度，并累积相应的水平位移。 这是正确的，因为它直接模拟了问题的定义：每个适用层在每次向上和向下传递时都会贡献一次风，但峰值层仅贡献一次。 然而，由于每只鸟可能需要检查所有风层，因此复杂度变为 O(nm)，这导致在最坏情况下大约需要 10^10 次操作，而且速度太慢。 

关键的观察结果是，风层的贡献与鸟的起始位置无关，仅取决于高度达到其最大高度的层组。 这表明按高度预先计算累积风效应。 如果我们按高度对风层进行排序并将所有效果压缩到前缀结构中，那么对于任何鸟类，我们都可以使用直到其高度的前缀和查询来回答其总水平移动。 这将问题减少到排序和前缀积累，而不是重复扫描。 

一旦我们按排序顺序处理风层，我们就可以维护水平位移的运行总计。 每只鸟只需查询其高度阈值的运行总数即可。 如果多个层共享相同的高度，我们会先聚合它们，然后再更新前缀和，以确保正确性。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了|
 | 按高度排序 + 前缀总和 | O((n + m) log m) | O((n + m) log m) | O(米) | 已接受 |

 ## 算法演练

 1. 读取所有风层并按高度对它们进行分组，总结它们的影响。 这确保了同一高度的多个急流被视为单个组合影响。 
2. 按升序对唯一的高度进行排序。 这使我们能够构建风效果的单调前缀累积。 
3、遍历排序后的风层，维护水平位移的运行前缀和。 在每个高度，将该高度处的总风效应添加到累积和中。 
4. 存储成对的（高度、累积偏移）。 这种结构允许快速查找任意高度的总风效应。 
5. 对于每只鸟，获取它的高度并使用二分查找找到最后一个不超过它的风高度。 相应的前缀值是该鸟经历的总水平移动。 
6. 将这个偏移添加到小鸟的初始位置并输出结果。 

微妙的推理步骤是，鸟类会受到高度最高为峰值的所有风层的影响。 由于我们已将所有贡献压缩到排序高度的前缀结构中，因此前缀值直接对这些效果进行精确编码，而无需模拟飞行路径。 

### 为什么它有效

 核心不变量是，按高度升序处理风层后，任意高度h处的前缀和代表高度≤h处所有急流引起的总水平位移。 每只具有峰值高度 h 的鸟都与该组急流相互作用，因为根据问题定义，它在上升和下降过程中穿过所有急流。 由于贡献是独立且相加的，并且没有更高的急流可以影响较低高度的鸟，因此前缀和既足够又准确。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from bisect import bisect_right

def solve():
    n, m = map(int, input().split())
    
    birds = []
    for _ in range(n):
        l, h = map(int, input().split())
        birds.append((l, h))
    
    jets = {}
    for _ in range(m):
        a, w = map(int, input().split())
        if a in jets:
            jets[a] += w
        else:
            jets[a] = w
    
    heights = sorted(jets.keys())
    
    prefix = []
    total = 0
    for h in heights:
        total += jets[h]
        prefix.append(total)
    
    ans = []
    for l, h in birds:
        idx = bisect_right(heights, h) - 1
        if idx >= 0:
            ans.append(str(l + prefix[idx]))
        else:
            ans.append(str(l))
    
    print(" ".join(ans))

if __name__ == "__main__":
    solve()
```该实现首先按高度压缩所有风层，以便将重复的高度合并为单个有效移位。 然后，排序后的高度列表允许使用前缀和数组来表示每个高度的累积风影响。 

对于每只鸟，二分搜索会找到不超过其峰值高度的最高风层。 该指数直接给出了正确的累积位移。 如果不存在这样的层，则小鸟不受影响并保留其起始位置。 

一个常见的实施陷阱是在构建前缀数组之前忘记合并具有相同高度的急流。 如果跳过此步骤，以后的累加可能会重复计算或乱序效果。 另一个微妙的问题是二分搜索中的差一错误，因为必须调整 bisect_right 才能获取最后一个有效索引。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from bisect import bisect_right

    def solve():
        n, m = map(int, input().split())
        birds = []
        for _ in range(n):
            l, h = map(int, input().split())

            if i >= 0:
                res.append(str(l + prefix[i]))
            else:
                res.append(str(l))

        return " ".join(res)

    return solve()

 ## 边缘情况

 当没有急流时，前缀结构为空，每只鸟都应该输出其原始位置。 该算法通过在应用移位之前检查是否存在任何有效的前缀索引来处理此问题。 

当多个急流共享相同高度时，它们会在前缀计算之前合并，因此不会存在排序歧义。 即使输入不唯一，这也确保累积效应是正确的。 

当所有急流都高于每只鸟的高度时，每次二分搜索都不会返回有效的索引，并且所有鸟都保持在其起始位置，这符合没有遇到风层的物理解释。
