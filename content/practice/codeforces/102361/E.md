 ## 解决方案
 ## 问题理解

 我们有一个`n × m`包含空单元格和阻塞单元格的网格。 每个机器人在网格上方的不同列中开始，最初向下移动。 每个出口都位于网格正下方的不同列中。 

机器人通常会继续直行。 改变方向的唯一方法是将四个角形转向装置之一放置在空单元上。 每个设备将单元的一个水平侧与一个垂直侧精确连接，因此从几何角度来看，它的行为就像一个角。 设备不能从不兼容的方向交叉。 

机器人可以占用同一个空单元，因此普通单元的占用不是容量限制。 困难在于转动装置占据了整个单元。 不使用该设备的机器人无法直接穿过该单元。 这在不同的机器人路径之间创建了有用的分离属性。 

对于每个测试用例，输入给出网格、所有机器人的起始列以及所有出口的列。 问题是我们是否可以放置转动装置，以便每个机器人最终到达某个出口，而不会接触到被封锁的单元格或从非法方向使用装置。 我们只需要输出`Yes`或者`No`。 

网格尺寸最多为`100 × 100`，所以最多有`10,000`细胞。 最多可以有`100`机器人。 一个解决方案大致为`O(nm)`或者`O(anm)`操作易于管理。 枚举单元配置的解决方案是没有希望的，因为即使在考虑机器人运动之前，每个空单元都有五种可能性：没有设备或四种设备方向之一。 配置数量可达`5^(nm)`，这对于`nm = 10,000`。 原始竞赛列表给出了一秒的时间限制，因此预期的解决方案需要利用网格结构而不是搜索配置。 

一些边缘情况很容易被错误处理。 

考虑一个被阻塞的单元格：```
1
1 1 1 1
1
1
1
```唯一的机器人在唯一的单元上方开始，唯一的出口在其下方。 由于单元格被阻塞，所以正确答案是`No`。 将每个源列直接连接到其垂直网格节点而不检查第一个单元格是否为空的实现将错误地接受它。 

同样的问题也出现在底部：```
1
1 1 1 1
1
1
1
```这里的网格被封锁，因此没有可用的路径通往出口。 更一般地，无法到达被堵塞的底部单元下方的出口。 该图必须仅将出口连接到空底部单元格的垂直状态。 

单行迷宫也需要小心，因为机器人可能需要水平转动，然后在同一行内再次向下转动：```
1
1 2 1 1
00
1
2
```答案是`Yes`。 机器人进入列`1`垂直，在第一个单元格中右转，在第二个单元格中向下转，然后从出口离开`2`。 假设每个垂直运动必须经过至少两个不同行的图表将错过这个有效的构造。 

最后，考虑官方的第二个示例：```
1
3 4 2 2
0000
0011
0000
3 4
2 4
```答案是`No`。 机器人从列开始`3`机器人从列开始`4`都可以接近出口`4`只能通过共享一个不能以所需方式被两条不同路径占用的转向结构来实现。 一种独立计算每个机器人的一条路径的简单可达性检查可以说`Yes`，因为每个机器人都有一条通往出口的路线。 真正的问题是所有路由是否可以共存于一个设备位置。 

## 方法

 直接的暴力方法是决定每个空单元格中发生什么。 每个单元格有五种选择：将其留空，或安装四个可能的角落设备之一。 对于配置，我们可以模拟每个机器人，同时记住其当前的单元格和方向。 由于状态是由一个单元和四个方向之一组成的对，因此确定性机器人最多可以模拟`4nm`在到达出口或重复某个状态之前的状态。 达到重复状态意味着机器人陷入循环。 

如果有`k`空单元格，配置计数为`5^k`。 在最坏的情况下`k = nm = 10,000`，所以即使只是枚举配置也需要`5^10000`案例。 添加最多模拟`a`机器人大致会给出`O(5^(nm) · a · nm)`，这是完全不可行的。 

有用的观察是，几何形状让我们暂时忘记了设备的确切方向。 从两个不同的角度思考细胞。 机器人可以在单元中垂直移动，也可以在单元中水平移动。 转动装置正是将这两种可能性联系起来的。 

对于每个空单元格`(i,j)`，创建两个图顶点。 让`V(i,j)`代表通过细胞的垂直运动，并让`H(i,j)`代表穿过细胞的水平运动。 

如果两个垂直相邻的单元格都是空的，则机器人可以在它们之间垂直继续前进`V`顶点。 类似地，两个水平相邻的空单元格之间相连`H`顶点。 

在一个空单元格内，连接`V(i,j)`和`H(i,j)`。 使用这种连接意味着在那里放置一个转动装置。 相应流的方向决定了需要四个角方向中的哪一个。 同一连接的两个相反方向对应于穿过同一角的两种合法方式。 

第二个几何观察可以解释为什么单位容量足够。 两个机器人不能共享一条有用的直线段，然后又分开。 如果将转动装置放置在它们的共享段上，则不转动的机器人必须直接穿过转动装置占据的单元，这是非法的。 如果不存在这样的设备，则两个机器人将保持相同的轨迹直到出口，并且不同的出口不能使共享轨迹成为两条不同的路线。 因此，可行的解决方案可以由不竞争相同水平或垂直轨道的路径来表示。 这是在轨道边缘使用容量一的关键原因。 该问题的标准解决方案正是使用这种两层网格结构和最大流量。 

源连接到`V(1,p)`对于从列开始的每个机器人`p`。 该模型模拟了每个机器人垂直进入第一排的事实。 对于每个出口列`e`， 连接`V(n,e)`到水槽，因为向下移动到达该单元格的底部意味着机器人可以离开迷宫。 

得到的图只有`O(nm)`顶点和边。 然后我们询问最大流量是否等于机器人的数量。 如果是这样，流程就会分解为有效的源到出口路径，并且水平和垂直状态之间的每个连接都会告诉我们在哪里放置转动设备。 如果最大流量小于机器人数量，则无法为某些机器人分配兼容路径。 

标准的编辑构造通常使用 Dinic 算法来实现。 由于每个相关容量都是 1，并且总期望流量最多为`a ≤ 100`，我们可以使用一种更简单的专用最大流实现：重复运行 BFS 来找到一条增广路径并通过它发送一个单元。 最多`a`增强是必要的。 这给出了一个`O(aE)`界，这里很容易就足够小了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(5^(nm) · a · nm)`|`O(nm)`| 太慢了 |
 | 最佳|`O(a · nm)`|`O(nm)`| 已接受 |

 ## 算法演练

 1. 为每个网格单元创建两个顶点，一个代表垂直运动，一个代表水平运动。 被阻挡的单元格没有可用的边缘。 分割是必要的，因为转弯正是从一种运动类型到另一种运动类型的过渡。 
2. 对于每对垂直相邻的空单元格，将它们在两个方向上的垂直顶点与容量连接起来`1`。 机器人可以沿着这个连接直线向上或向下移动。 该容量代表两个可行的机器人轨迹不能竞争同一有向轨道的事实。 
3. 对于每对水平相邻的空单元，将它们在两个方向上的水平顶点与容量连接起来`1`。 这相当于上一步的水平方向。 
4. 对于每个空单元格，将其水平顶点和垂直顶点在两个方向上用容量连接起来`1`。 使用该边缘意味着该单元包含一个转动装置。 例如，从上方进入垂直状态并通过水平状态离开的流对应于适当的`NE`或者`NW`设备取决于流动所采取的水平方向。 反向运动给出相应的合法反向遍历。 
5. 添加超级源和超级接收器。 对于列中的每个机器人`p`，将源连接到`V(1,p)`有能力`1`，前提是第一个单元格为空。 容量 1 代表一台机器人从那里开始。 
6. 对于列的每个出口`e`， 连接`V(n,e)`到有容量的水槽`1`，前提是底部单元格为空。 机器人离开迷宫时必然是向下运动的，因此出口属于垂直层。 
7. 计算从源到汇的最大流量。 我们在残差图上重复运行 BFS，用父指针恢复一条增广路径，并将流量增加一。 由于每个原始边的容量为一，因此我们最多只需要`a`流量单位，不超过`a`需要进行增强。 
8. 将结果流与`a`。 如果流量等于机器人数量，则打印`Yes`。 否则打印`No`。 

### 为什么它有效

 中心不变量是每条从源到汇的流动路径都描述一条合法的机器人轨迹。 沿着垂直边缘移动意味着继续垂直穿过相邻的空单元格。 沿着水平边缘移动意味着继续水平穿过相邻的空单元格。 在两层之间切换意味着将一个角落设备放置在该单元中。 由于每个此类过渡都具有单位容量，因此构造无法将相同的定向转向资源或直线轨道分配给两个不兼容的机器人路径。 

相反，采取任何有效的转动装置布置。 跟踪每个机器人从起点到出口，并记录它在每个单元格是垂直还是水平移动。 直线运动成为一层内的边缘，而每个合法的转弯成为两层之间的边缘。 由此产生的机器人轨迹形成源到汇的流动路径。 几何分离属性可防止冲突路径需要相同的单位容量资源。 因此，每一个有效的逃生安排都会产生价值流`a`，以及每一个价值流`a`给出一组可实现的机器人轨迹。 通过最大流量表征，检查最大流量是否为`a`这正是所需的决定。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline
sys.setrecursionlimit(1_000_000)

def solve_case(n, m, a, b, grid, robots, exits):
    cells = n * m
    source = 2 * cells
    sink = source + 1
    vertex_count = sink + 1

    # Forward-star representation of the residual graph.
    head = [-1] * vertex_count
    to = []
    cap = []
    nxt = []

    def add_edge(u, v, c):
        idx = len(to)
        to.append(v)
        cap.append(c)
        nxt.append(head[u])
        head[u] = idx

        to.append(u)
        cap.append(0)
        nxt.append(head[v])
        head[v] = idx + 1

    def add_bidir(u, v):
        add_edge(u, v, 1)
        add_edge(v, u, 1)

    def hnode(i, j):
        return (i * m + j) * 2

    def vnode(i, j):
        return (i * m + j) * 2 + 1

    # Source to robots and bottom cells to sink.
    for p in robots:
        j = p - 1
        if grid[0][j] == '0':
            add_edge(source, vnode(0, j), 1)

    for e in exits:
        j = e - 1
        if grid[n - 1][j] == '0':
            add_edge(vnode(n - 1, j), sink, 1)

    # Grid graph.
    for i in range(n):
        for j in range(m):
            if grid[i][j] != '0':
                continue

            v = vnode(i, j)
            h = hnode(i, j)

            # A turn in this cell.
            add_bidir(h, v)

            # Continue vertically.
            if i > 0 and grid[i - 1][j] == '0':
                add_bidir(vnode(i - 1, j), v)

            # Continue horizontally.
            if j > 0 and grid[i][j - 1] == '0':
                add_bidir(hnode(i, j - 1), h)

    flow = 0

    # Since all useful capacities are one and a <= 100, repeatedly
    # finding one augmenting path is fast enough.
    while flow < a:
        parent = [-1] * vertex_count
        parent[source] = -2

        q = deque([source])

        while q and parent[sink] == -1:
            u = q.popleft()
            e = head[u]

            while e != -1:
                if cap[e] > 0:
                    v = to[e]
                    if parent[v] == -1:
                        parent[v] = e
                        if v == sink:
                            break
                        q.append(v)
                e = nxt[e]

        if parent[sink] == -1:
            break

        # Every augmenting path carries exactly one unit.
        v = sink
        while v != source:
            e = parent[v]
            cap[e] -= 1
            cap[e ^ 1] += 1
            v = to[e ^ 1]

        flow += 1

    return flow == a

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        n, m, a, b = map(int, input().split())
        grid = [input().strip() for _ in range(n)]
        robots = list(map(int, input().split()))
        exits = list(map(int, input().split()))

        answers.append(
            "Yes" if solve_case(n, m, a, b, grid, robots, exits)
            else "No"
        )

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```该图为每个单元格使用两个整数 ID。`hnode(i, j)`是水平状态并且`vnode(i, j)`是垂直状态。 保持两种状态分开，可以让单个单元格代表直线运动的可能性和可能的​​转弯。 

这`add_bidir`助手值得关注。 双向容量一连接被实现为两个独立的定向容量一边缘。 每个有向边还接收其自己的剩余边。 这与添加一对普通残差边不同，因为两个方向上的移动在物理上都是可能的。 

源仅连接到空的第一行单元格。 这可以避免机器人意外地进入被封锁的单元。 在将出口连接到水槽之前，对底行执行相同的检查。 

图形构造仅检查上方的单元格和左侧的单元格。 加工时`(i,j)`，这些邻居的对应边之前尚未添加，因此每个无向网格邻接只插入一次。`add_bidir`然后创建两个方向。 

流搜索在剩余边缘上使用 BFS。`parent[v]`存储用于首先到达的边缘`v`，允许从接收器重建完整的增广路径。 由于每次增广都只增加一个单位，并且最多有`100`robots，循环最多在之后终止`100`成功的增强。 Python 中不可能出现整数溢出，事实上所有容量和答案最多都是`100`。 

该代码在内部使用从零开始的网格坐标。 输入列是从一开始的，因此每个机器人或出口列都转换为`p - 1`。 这是在该实现中容易导致错误的主要索引细节。

 官方示例包含两个测试用例。 以正常的多行形式编写，它是：```
2

0000
0011

2 4

```对于第一种情况，两个机器人可以使用单独的转动结构。 一条路线从列开始`1`，走到最后一排，右转，从出口离开`2`。 另一个从列开始`4`，在顶部附近左转，向下穿过列`3`，在底部附近右转，然后从出口离开`4`。 

| 增强| 源机器人| 主图路线| 流量|
 | --- | --- | --- | --- |
 | 1 | 第 1 栏 | 垂直列 1 → 水平行 3 → 垂直列 2 → 水槽 | 1 |
 | 2 | 第 4 栏 | 垂直列 4 → 水平行 1 → 垂直列 3 → 水平行 3 → 垂直列 4 → 水槽 | 2 |

 第二次增强后，流量等于`a = 2`，所以算法打印`Yes`。 该轨迹演示了为什么机器人可以多次转动，以及为什么两层表示足以对所有四个设备方向进行编码。 

对于第二种情况，机器人按列开始`3`和`4`。 来自专栏的机器人`4`可以导向出口`4`，但是来自列的机器人`3`也需要相同的下部转弯结构才能到达出口`4`同时避免行中被阻挡的单元格`2`。 残差网络只能找到一条兼容的源到汇路径。 

| 增强| 源机器人| 结果 | 流量|
 | --- | --- | --- | --- |
 | 1 | 第 3 列或第 4 列之一 | 到达可用的退出路径 | 1 |
 | 2 | 剩余机器人 | 没有剩余增广路径| 1 |

 最大流量为`1`，小于`a = 2`，所以答案是`No`。 这说明了为什么单独检查每个机器人的可达性是不够的。 这些路径必须在相同的网格和设备约束下共存。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(a · nm)`| 该图有`O(nm)`边缘，并且至多`a ≤ 100`执行单位增强。 |

 |`1 × 2`带网格`00`， 机器人`1`， 出口`2`|`Yes`| 边界转弯和单行运动|
 |`100 × 100`100 个机器人和 100 个出口全部为零 |`Yes`| 最大尺寸、最大流量值和大图构造 |
 |`2 × 2`， 网格`00 / 01`, 退出栏`2`|`No`| 底部出口和边界索引受阻 |

 ## 边缘情况

 在任何流离开源之前，会处理阻塞的起始单元情况。 为了```
1
1 1 1 1
1
1
1
```唯一的网格单元被阻挡，因此源根本没有接收到边缘。 BFS立即发现sink不可达，流量保持`0`，结果是`No`。 

受阻的出口单元表现出对称性。 考虑```
1
2 2 1 1
00
01
1
2
```机器人在柱上方启动`1`，而唯一的出口位于列下方`2`。 虽然第一行是开放的，但列中的底部单元格`2`被阻止。 该实现拒绝添加边缘`V(2,2) -> sink`，因此没有路径可以在该出口处终止。 最大流量为`0`，生产`No`。 

单行边界情况更为微妙：```
1
1 2 1 1
00
1
2
```源连接到单元的垂直状态`(1,1)`。 第一个转弯使用之间的边缘`V(1,1)`和`H(1,1)`，水平边缘移动到`H(1,2)`，第二回合移动到`V(1,2)`。 最后`V(1,2)`连接到水槽。 流量为`1`，所以答案是`Yes`。 没有特殊情况`n = 1`是需要的，因为图形表示已经自然地处理它。 

官方第二个示例捕获了共享路径的情况：```
1
3 4 2 2
0000
0011
0000
3 4
2 4
```这两个机器人都有各自合理的路线，但所需的路线争夺相同的单位容量结构。 一旦一条路线消耗了该资源，第二个来源就没有剩余的出口路径。 最大流量停止于`1`，而需要两个单位，因此算法返回`No`。 

最大尺寸全空情况测试相反的极端：```
100 × 100 grid of zeros
100 robots in columns 1 through 100
100 exits in columns 1 through 100
```每个机器人都可以简单地继续向下，而无需使用转向装置。 该图包含所有`20,000`运动状态，但源到汇的流动具有确切的价值`100`。 这证实了当直线路径已经存在时，该实现不会意外地需要转弯，并且图形在最大维度上仍然是可管理的。
