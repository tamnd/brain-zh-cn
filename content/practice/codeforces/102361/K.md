 ## 解决方案
 ## 问题理解

 我们有一棵有根树，以顶点 1 为根。 移动包括删除当前叶子的任何非空集，其中叶子是没有剩余子节点的顶点。 一次移除几片叶子是允许的，它们的父母可能会成为下一步移动的叶子。 玩家轮流进行，移除最后剩余顶点的玩家获胜，因为另一个玩家没有合法的移动。 任务是判断初始位置是否为第一名玩家获胜，`Takeru`，或者第二个玩家获胜，`Meiya`。 官方问题正是使用了这种有根树公式，并允许测试用例中所有树大小的总和达到 (10^6)。 

父数组包含从 2 到 (n) 的每个顶点的父顶点。 我们只需要每个顶点的父关系和子节点的数量。 约束 (n\le 10^6) 以及所有测试用例总和的相同界限排除了任何状态空间博弈搜索。 即使 (O(n\log n)) 原则上也是可以接受的，但游戏的结构让我们可以将解决方案简化为线性时间和线性内存。 

有两种边缘情况很容易被误处理。 首先，父节点有多个子节点的顶点比链末端的普通叶子更重要。 例如，```
1
4
1 1 2
```根 1 具有子级 2 和 3，顶点 2 具有子级 4。顶点 3 是叶子，其父级有两个子级。 正确答案是`Takeru`。 如果粗心的解决方案仅计算每个叶子的深度奇偶性，则可能会错过这个结构性的获胜位置。 原因是 Takeru 可以将这样的一片叶子连同任何叶子一起移除，在移除该叶子后形成获胜响应。 

第二种边缘情况是一棵分支树，其叶子到分支的链都具有偶数长度。 例如，```
1
5
1 1 2 3
```具有根 1，其子代为 2 和 3，而 2 具有子代 4，3 具有子代 5。两个叶链是 (4\rightarrow2) 和 (5\rightarrow3)，每个在到达分支根之前包含两个顶点。 正确答案是`Meiya`。 基于普通根到叶深度的解决方案将无法捕获相关分解，因为两个分支共享根。 

纯链是另一种边界情况。 为了```
1
3
1 2
```每回合都只有一个可用的叶子，因此游戏持续三步，答案是`Takeru`。 对于四个顶点，```
1
4
1 2 3
```游戏持续四步，答案是`Meiya`。 这就是为什么链长度必须包括叶子本身，并且当整棵树是一条链时，还包括根。 

## 方法

 直接的做法是将局面视为一场公正的博弈，并递归地枚举每一个可能的着法。 如果当前树有 (k) 个叶子，则有 (2^k-1) 个非空叶子子集可以被删除。 我们可以递归地评估每棵生成的树并记住其获胜状态。 这是正确的，因为当至少一个合法动作达到亏损位置时，该位置就获胜。 

问题在于选择的数量。 考虑一个 (n) 顶点星，其根直接连接到所有 (n-1) 个其他顶点。 第一个玩家已经有

 [
 2^{n-1}-1
 ]

 不同的法律行动。 因此，即使是穷举搜索的第一级也是指数级的。 一般状态空间实现也可能需要指数内存，因此此方法对于 (n=10^6) 不可用。 

关键的观察结果是，分支顶点将树分成独立的顶点链，并且只有一个子节点。 考虑一片叶子并向上移动，而每个遇到的顶点都有一个子节点。 由此产生的最大路径是一条链，其唯一有意义的信息是其长度奇偶性。 一旦我们区分了叶子是否有兄弟姐妹，游戏就变得特别简单。 

假设某个叶子 (x) 的父节点至少有两个子节点。 那么该位置立即赢得玩家的移动。 删除 (x)。 如果结果是亏损，我们就完蛋了。 如果获胜，则从结果位置采取获胜棋步，并将 (x) 添加到同一棋步中。 删除 (x) 无法在其他地方创建另一个叶子，因为它的父级仍然有另一个子级，因此该获胜动作使用的每个顶点在删除 (x) 之前就已经是叶子了。 我们在最初的一步棋中再次陷入了失败的境地。 这是中心结构引理。 

排除这种情况后，没有叶子有兄弟姐妹。 每片叶子都属于一个最大链，其内部顶点每个都有一个子节点。 将链长度定义为从叶子向上的顶点数，在具有至少两个子节点的第一个祖先之前停止。 如果整棵树是一条链，则根作为链的末端包含在内。 

现在奇偶校验完全决定了结果。 如果某个链的长度为奇数，则第一个玩家可以一次移动移除每个奇数长度链末端的叶子。 因为不存在具有兄弟姐妹的叶子，所以每个这样的链的长度至少为二，除非整棵树是一个链。 移除其叶子会将奇数长度更改为偶数长度，而不会暴露分支顶点。 结果位置只有偶数链。 

如果每条链都是偶数，则该位置正在丢失。 任何移动都会从至少一条链上移除叶子，从而将每个受影响的链从偶数变为奇数。 如果受影响的链长度变为一，则其叶子现在有一个分支父代，立即为下一个玩家提供获胜的结构案例。 否则，剩下一条奇数链，而奇数链本身就是获胜位置。 因此，从全平位置开始的每一步棋都会给对手带来胜利的位置。 

这产生了一个特别小的标准：答案是`Takeru`如果某个叶子的父代有多个子代，或者某个最大叶链的长度为奇数。 否则答案是`Meiya`。 这种表征和线性时间实现也在独立竞赛解决方案文章中给出。

 ## 算法演练

 1. 读取每个顶点的父顶点并计算每个顶点的子顶点数。 子计数立即告诉我们某个顶点是否是分支点。 
2. 扫描所有具有零个子节点的顶点。 这些正是原始树的当前叶子。 对于每个叶子 (v)，首先检查其父节点。 如果父母至少有两个孩子，则返回`Takeru`立即，因为结构性获胜引理适用。 
3. 如果父顶点恰好有一个子顶点，则在当前顶点的父顶点仍然仅有一个子顶点时向上遍历链。 链长度从 1 开始，因为叶子本身属于链。 每次我们移动到它的父级，长度就增加 1。 
4. 当当前顶点是根顶点或其父顶点是分支顶点时停止。 分支顶点不是该链的一部分，而如果树本身是单链，则包含根。 
5. 如果此链长度为奇数，则返回`Takeru`。 移除每条奇数链末端的叶子会让对手处于所有链长度都是偶数的位置，这是失败的。 
6. 如果每个叶子都产生偶数链长并且没有叶子有分支父代，则返回`Meiya`。 每个可能的移动都会创建一条奇数链或一个其父级有分支的叶子，因此下一个玩家总是会获得获胜位置。 

向上行走仍然是线性的原因是我们只遍历只有一个子节点的顶点。 这样的一个顶点恰好属于一个叶子链，因此它不能被两个不同的叶子遍历。 分支顶点终止行走。 因此，尽管实现似乎包含嵌套循环，但所有叶节点的迭代总数为 (O(n))。 

### 为什么它有效

 获胜位置有两种。 第一个包含一个叶子，其父节点至少有两个子节点。 第一个玩家总是可以将那片叶子合并到导致失败位置的移动中。 第二个包含奇数长度的最大叶链。 删除所有奇数链的末端叶子会将每个相关链长度从奇数更改为偶数，从而产生丢失位置。 

当两种获胜条件都不存在时，每个最大叶链都是偶数，并且每个叶都有一个唯一的无兄弟父链。 任何一步都会将至少一个偶数链变成奇数链。 如果链的长度减少到一，则其父节点是分支顶点，并且结构获胜条件出现。 否则直接保留一条奇数链。 因此，从全偶位置开始的每一步都会导致获胜位置，从而使原始位置失败。 这准确地建立了算法使用的标准。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())

        parent = [0] * (n + 1)
        child_count = [0] * (n + 1)

        data = list(map(int, input().split()))

        for i, p in enumerate(data, 2):
            parent[i] = p
            child_count[p] += 1

        winning = False

        for v in range(2, n + 1):
            if child_count[v] != 0:
                continue

            p = parent[v]

            # A leaf with a sibling is an immediate winning position.
            if child_count[p] > 1:
                winning = True
                break

            # Count vertices in the maximal degree-1 chain.
            length = 1
            u = v

            while u != 1 and child_count[parent[u]] == 1:
                u = parent[u]
                length += 1

            if length & 1:
                winning = True
                break

        out.append("Takeru" if winning else "Meiya")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```这`parent`数组存储每个顶点的父顶点，而`child_count`记录孩子的数量。 不需要邻接表，因为该算法仅从叶子向上行走。 

循环从顶点 2 开始，因为顶点 1 是根且 (n\ge2)，因此根最初不可能是叶子。 对于每片叶子，`child_count[p] > 1`在任何链遍历之前处理立即获胜条件。 

链长度从 1 开始，因为叶子本身就是链的一部分。 循环检查`u != 1`访问之前`parent[u]`，这避免了根没有父级的特殊情况。 当到达根时，它已经被计数，这给出了纯链的正确结果。 例如，三顶点链产生长度 3 并且获胜，而四顶点链产生长度 4 并且失败。 

条件`child_count[parent[u]] == 1`意味着父级仍在当前单子链内。 如果其子节点数大于 1，则该父节点是分支顶点，不得包含在内。 该边界是该问题中许多差一错误的根源。 

Python 整数在这里不存在溢出问题。 每个存储的值最多为 (10^6)，并且该算法仅执行整数比较、增量和数组访问。 

包含 (n-1) 个父级的输入行最多可以包含近一百万个整数。 将该行转换一次`map`和`list`保持解析简单并避免重复调用`input()`对于单个顶点。

 ## 边缘情况

 对于最小树```
1
2
1
```顶点 2 是唯一的叶子节点，而顶点 1 仅有一个子节点。 链遍历计数顶点 2，然后计数顶点 1，产生长度 2。由于长度是偶数并且没有分支叶子，所以答案是`Meiya`。 第一个玩家移除顶点 2，第二个玩家移除根。 

对于分支父案例```
1
4
1 1 2
```顶点 3 和 4 是叶子。 顶点 3 有父节点 1，根 1 有两个子节点，因此算法立即返回`Takeru`。 具体的获胜策略是将顶点 3 和 4 一起删除。 这留下了双顶点链（1\rightarrow2），这是下一个玩家的失败位置。 此示例演示了为什么必须在链奇偶校验之前检查分支条件。 

对于纯奇数链```
1
3
1 2
```唯一的叶子是顶点 3。它的父节点有一个子节点，因此算法遵循 (3\rightarrow2\rightarrow1)，计算三个顶点。 奇怪的结果给出`Takeru`。 包含根是因为没有终止链的分支祖先。 

对于纯偶数链```
1
4
1 2 3
```同样的遍历得到 (4\rightarrow3\rightarrow2\rightarrow1)，长度为 4。结果是`Meiya`。 这捕获了计算边而不是顶点的常见错误。 有 3 个边但有 4 个顶点，游戏结果遵循顶点数。 

对于偶数分支情况```
1
5
1 1 2 3
```叶子是 4 和 5。叶子 4 跟随 (4\rightarrow2) 并停止，因为它的父节点（顶点 1）有多个子节点。 它的链长度是 2。叶子 5 类似地给出长度 2。没有叶子有分支父代，并且每个链都是偶数，因此算法打印`Meiya`。 

对于最大尺寸的恒星，每个父值都是 1：```
1
1000000
1 1 1 ... 1
```每个非根顶点都是一个叶子，而根 1 有 (999999) 个子节点。 检查的第一个叶子已经满足分支父条件，因此算法可以停止而不遍历任何链。 结果是`Takeru`。 这种情况同时运用了最大值 (n) 和提前退出行为，即使叶子数量巨大，也能保持实现效率。
