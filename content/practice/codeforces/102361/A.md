 ## 解决方案
 ## 问题理解

 对于每个查询点（A），我们必须选择两个不同的原始点（P_u）和（P_v）。 这三个点必须形成一个非退化三角形，其中一个角度等于 (90^\circ)。 该查询的输出是此类无序原始点对的数量。 

关键的几何条件用向量表示。 如果 (A) 是直角顶点，则

 [
 (P_u-A)\cdot(P_v-A)=0。 
]

 然而，(A) 也可以位于斜边上。 在这种情况下，某个原点 (P_i) 是直角顶点，并且条件变为

 [
 (A-P_i)\cdot(P_j-P_i)=0。 
]

 这两种情况之间的区别驱动了整个解决方案。 

最多有 (2000) 个原始点和 (2000) 个查询。 单个查询大约有 200 万个可能的原始点对，并且为每个查询执行此操作将需要以最大大小进行大约 (4\times10^9) 对检查。 官方裁判给这个问题的时间限制是4秒，所以看立方体的方法远远超出了我们的承受能力。 

坐标可以达到(10^9)，因此差值可以达到(2\times10^9)，点积大致可以达到(4\times10^{18})。 Python 整数直接处理这些值，而固定宽度的实现则需要 64 位算术。 

第一个微妙的情况是来自同一顶点的多个向量沿着同一条线。 例如：```
3 1
1 0
-1 0
0 1
0 0
```正确的输出是`2`。 两个水平点形成一条方向线，垂直点形成一条垂直线，因此水平端点有两种选择。 存储原始向量而不是其方向的粗心实现可能会忽略 ((1,0)) 和 ((-1,0)) 属于同一几何线的事实。 

第二个微妙的情况是查询本身不必是直角顶点。 例如：```
2 1
0 0
1 0
0 1
```正确的输出是`1`。 直角位于 ((0,0))，而不是查询点 ((0,1))。 仅计算查询周围的垂直向量的方法将错误地返回零。 

第三种边缘情况发生在同一垂直或水平线上的点上：```
4 1
0 0
0 1
0 2
0 3
1 1
```正确的输出是`4`。 相等的 (x) 坐标强制许多向量垂直，因此这种情况会捕获不正确的斜率处理，特别是除以 (x) 分量或以不一致的方式单独处理垂直方向的代码。 

最后，保证查询点与每个原始点都不同。 因此，从查询或原始点到另一个相关点的向量永远不会是 ((0,0))。 这很重要，因为方向归一化除以 gcd，并且 ((0,0)) 的 gcd 将为零。 

## 方法

 直接暴力解决方案考虑每个查询 (A)、每对 (P_u,P_v)，并检查三角形是否是直角。 一个查询有 (\binom n2) 对，因此总工作量为

 [
 O(qn^2)。 
]

 在 (n=q=2000) 处，这是

 [
 2000\binom{2000}{2}=3,998,000,000
 ]

 配对检查。 测试本身是恒定时间，但近 40 亿次迭代已经太多了，尤其是在 Python 中。 

蛮力之所以有效，是因为每个可能的三角形都会被直接检查。 问题在于它忽略了垂直度仅取决于方向而不取决于矢量长度的事实。 

假设点 (O) 是固定的。 考虑从 (O) 到相关点的所有向量。 当两个这样的向量的方向线垂直时，它们正好形成直角。 我们可以将每个非零向量标准化为其无向线的规范表示。 对于向量 ((x,y))，将两个坐标除以 (\gcd(|x|,|y|))，然后选择一致的符号，以便 (x>0) 或 (x=0) 且 (y>0)。 

例如，所有

 [
 (1,2),\四元 (2,4),\四元 (-1,-2),\四元 (-2,-4)
 ]

 成为相同的规范方向 ((1,2))。 

一旦方向 (d=(x,y)) 被标准化，垂直方向就简单地为 ((-y,x))，然后进行相同的标准化。 哈希映射可以存储属于每个方向的向量数量，因此垂直查找的预期时间为 (O(1))。 

查询点仍然有两个几何角色。 如果查询是直角顶点，我们可以在 (O(n\log C)) 中独立处理该查询，其中 (C) 是坐标大小，因为每个 (n) 向量都必须标准化。 

如果查询不是直角顶点，我们就无法独立处理查询周围的每一对。 相反，我们扭转了观点。 固定一个原点（P_i）作为直角顶点。 为 (P_i) 周围的所有其他原始点构建方向频率图。 然后每个查询（A）询问来自（P_i）的向量垂直于（A-P_i）的原始点的数量。 当这张地图可用时，我们可以回答所有 (q) 个查询。 对每个原始点重复此操作会给出 (O(n^2+nq)) 方向操作。 

这两种情况一起将工作量从数十亿次配对检查减少到大约几百万次哈希映射操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(qn^2)) | (O(1)) | (O(1)) | 太慢了 |
 | 方向散列 | (O((nq+n^2)\log C)) 预期 | (O(n)) | (O(n)) | 已接受 |

 这里（C）表示坐标差的大小。 对数因子来自欧几里得算法`gcd`。 

## 算法演练

 1.在处理第二种情况之前读取所有原始点和所有查询点。 这使得对于固定的原始直角顶点的计算完全离线，因为每个查询都是已知的。 
2. 定义方向归一化函数。 对于非零向量 ((dx,dy))，将两个坐标除以它们的 gcd，并在 (dx<0) 或 (dx=0) 和 (dy<0) 时翻转两个符号。 结果表示一条穿过原点的无方向线。 

我们故意识别相反的向量。 对于垂直度来说，((1,0))和((-1,0))起着完全相同的作用，将它们分开只会使计数更加复杂。 
3. 对于每个查询 (A)，构建 (n) 个方向 (P_i-A) 的频率图。 对于每个方向 (d) 出现 (c_d) 次，计算其规范垂直方向 (d^\perp)。 这两个方向类贡献的对的数量是(c_d c_{d^\perp})。 
4. 将所有方向类别的这些乘积相加并除以二。 从每个端点方向都会遇到一次一对垂直方向，因此如果没有除法，每个有效对都会被计数两次。 
5. 使用查询本身是直角顶点时获得的值初始化答案数组。 这考虑了 (90^\circ) 角度位于查询点的每个三角形。 
6. 固定一个原点(P_i)作为可能的直角顶点。 构建包含每个 (j\ne i) 的归一化方向 (P_j-P_i) 的频率图。 
7. 对于每个查询 (A_k)，标准化 (A_k-P_i)，使用 ((-y,x)) 将其旋转 (90^\circ)，标准化垂直方向，然后在地图中查找。 存储的频率正是使得(P_i,A_k,P_j)在(P_i)处具有直角的原始点(P_j)的数量。 
8. 将该频率添加到查询 (A_k) 的答案中。 对每个原始点 (P_i) 重复前两个步骤。 

查询的不是直角顶点的三角形恰好有一个作为直角顶点的原始点，因此单独处理每个 (P_i) 会将每个这样的三角形恰好计数一次。 
9. 打印每个查询的累积答案。 

### 为什么它有效

 对于固定顶点 (O)，两个非零向量 (u) 和 (v) 在方向线垂直时恰好垂直。 方向归一化保留了由向量表示的线，并且将归一化方向旋转 (90^\circ) 精确地给出了其垂直方向。 

当查询是直角顶点时，频率图对来自查询的向量垂直的每对原始点进行计数。 每个无序对在总和中出现两次，每个方向类出现一次，因此除以二即可准确得出三角形的数量。 

当原点(P_i)为直角顶点时，向量(A-P_i)决定向量(P_j-P_i)必须具有的方向。 该地图准确地包含了 (P_i) 中所有可能的原点方向的频率，因此查找准确地计算了 (P_j) 的有效选择。 由于每个三角形只有一个直角顶点，因此斜边上有查询的每个三角形都会被计数一次。 这两种情况是不相交的，因为非退化三角形只有一个直角。 

## Python 解决方案```python
import sys
from math import gcd

input = sys.stdin.readline

def normalize(dx, dy):
    g = gcd(abs(dx), abs(dy))
    dx //= g
    dy //= g

    if dx < 0 or (dx == 0 and dy < 0):
        dx = -dx
        dy = -dy

    return dx, dy

def solve(data=None):
    if data is None:
        read = input
        n, q = map(int, read().split())
        points = [tuple(map(int, read().split())) for _ in range(n)]
        queries = [tuple(map(int, read().split())) for _ in range(q)]
    else:
        it = iter(map(int, data.split()))
        n = next(it)
        q = next(it)
        points = [(next(it), next(it)) for _ in range(n)]
        queries = [(next(it), next(it)) for _ in range(q)]

    ans = [0] * q

    # Case 1: the query point itself is the right-angle vertex.
    for qi, (ax, ay) in enumerate(queries):
        freq = {}

        for px, py in points:
            d = normalize(px - ax, py - ay)
            freq[d] = freq.get(d, 0) + 1

        total = 0

        for (x, y), cnt in freq.items():
            px, py = normalize(-y, x)
            total += cnt * freq.get((px, py), 0)

        ans[qi] = total // 2

    # Case 2: an original point is the right-angle vertex.
    for ox, oy in points:
        freq = {}

        for px, py in points:
            dx = px - ox
            dy = py - oy

            if dx == 0 and dy == 0:
                continue

            d = normalize(dx, dy)
            freq[d] = freq.get(d, 0) + 1

        for qi, (ax, ay) in enumerate(queries):
            dx = ax - ox
            dy = ay - oy

            d = normalize(-dy, dx)
            ans[qi] += freq.get(d, 0)

    result = "\n".join(map(str, ans))

    if data is None:
        sys.stdout.write(result + "\n")
    else:
        return result + "\n"

if __name__ == "__main__":
    solve()
```这`normalize`函数是几何核心。 gcd 删除了向量的不相关长度，而符号约定将方向与其相反方向合并。 输入保证意味着传递给的向量`normalize`永远不会为零。 

第一个外循环处理查询是直角顶点的情况。 其频率图包含从查询到原始点的每条不同方向线的一个条目。 向上查找旋转方向会发现所有点都位于垂直线上。 

这`total // 2`该操作是必要的，因为如果方向 (d) 垂直于方向 (e)，则循环会处理 (d) 和 (e)。 因此，同一对点类别被包含两次。 

第二个外循环将每个原始点固定为直角顶点。 频率图仅包含其他原始点，因此固定点本身永远不会意外地形成零向量。 对于每个查询，从固定点到查询的向量旋转 (90^\circ)、归一化并用作字典键。 

该代码使用 Python 的任意精度整数，因此涉及 (2\times10^9) 左右坐标差的乘积是安全的。 不使用浮点斜率或角度计算，这避免了垂直线和非常大的坐标的精度误差。

 ## 边缘情况

 重复方向的情况通过标准化处理。 为了```
3 1
1 0
-1 0
0 1
0 0
```两个水平向量变为相同的规范方向 ((1,0))，而垂直向量为 ((0,1))。 频率图包含计数 (2) 和 (1)，因此查询直角计算给出 (2\cdot1=2)。 输出是`2`。 相反的向量被故意合并，因为垂直度取决于线，而不是向量指向的方向。 

斜边查询情况由第二阶段处理。 为了```
2 1
0 0
1 0
0 1
```将 ((0,0)) 固定为原始直角顶点可得到垂直的向量 ((1,0)) 和 ((0,1))。 查询从该固定顶点接收一个贡献，因此输出为`1`。 第一阶段贡献为零，这正是我们想要的，因为查询本身不是直角顶点。 

垂直线情况使用与其他方向相同的归一化。 为了```
4 1
0 0
0 1
0 2
0 3
1 1
```查询有向量 ((-1,-1))、((-1,0))、((-1,1)) 和 ((-1,2))。 ((-1,-1)) 和 ((-1,1)) 是垂直的，给出一个以查询为直角顶点的三角形。 原始点 ((0,1)) 也是与查询向量 ((1,0)) 的直角顶点，垂直于朝向 ((0,0))、((0,2)) 和 ((0,3)) 的三个垂直向量。 这又增加了三个，给出了正确的输出`4`。 

边界坐标情况使用大小差异 (2\times10^9)。 为了```
3 1
1000000000 1000000000
-1000000000 1000000000
1000000000 -1000000000
-1000000000 -1000000000
```该查询有一个水平向量 ((1000000000,-1000000000)) 和一个垂直向量 ((1000000000,1000000000))，产生一个直角。 Python的整数运算准确地表示了相应的乘积，因此输出为`1`。 

无效的全等点情况不需要特殊分支。 如果输入两次包含相同的点，则会违反问题保证，并可能创建一个零向量，而该向量的方向归一化是未定义的。 由于每个查询和每个原始点都是成对不同的，因此实现可以安全地假设传递给的每个向量`normalize`是非零的。
