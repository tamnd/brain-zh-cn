 ## 解决方案
 ## 问题理解

 我们有一个（n\times n）棋盘，每个单元格中最多包含一个棋子。 每块都是白色或黑色，并具有正去除值。 如果白色和黑色的棋子当前从左下方向暴露，则可以一起移除白色和黑色的棋子。 这样一对的价格是其价值的绝对差。 单件也可能因自身价值而随时被移除。 

曝光条件是不寻常的部分。 对于 ((x,y)) 处的一块，每当 (x'\ge x) 和 (y'\le y) 时，((x',y')) 处的另一块就会阻塞它。 换句话说，没有任何东西可以留在该作品的弱下方和弱左侧。 我们需要移除每一块所需的最小总成本。 

原始竞赛有 (n\le12) 个，时间限制为 1 秒，内存为 1024 MB。 棋盘可以包含多达 (12^2=144) 个棋子，因此棋子上的子集 DP 最多可以有 (2^{144}) 个状态。 这远远超出了可能的范围。 (n) 的较小值（而不是潜在的大量棋子）表明有用状态应该描述棋盘的边界。 当 (n=12) 时，仅存在 (\binom{24}{12}=2,704,156) 个单调边界，该边界很大，但可以用低级语言进行管理，并且可以轻松适应给定的内存限制。 这种轮廓-DP观点也是该问题的标准解决方向。 

有几种边缘情况无法直接进行贪婪解释。 单件必须单独处理。 为了```
1
W
7
```答案是（7），因为没有黑色棋子可以与之配对。 仅搜索对的解决方案将错误地返回零或留下未处理的部分。 

一对同等价值的物品可以成本为零，但它们仍然必须同时暴露。 考虑```
2
W.
.B
5 0
0 5
```两块都已暴露，因此可以将它们一起移除，成本为 (0)。 假设每对都需要正的单次移除成本的解决方案将错过这一点。 

相反的情况则更为微妙。 考虑```
2
WB
B.
5 7
7 0
```((2,1)) 处的黑色棋子阻挡了它上面的两个棋子，因此它是最初唯一相关的暴露棋子。 单独移除它需要花费 (7)。 然后，第一行中的白色和黑色棋子同时曝光，并且可以按成本 (2) 配对。 答案是（9）。 粗心的算法可能会立即将第一行的两个块配对，因为它们的单元格看起来兼容，即使左下角的阻塞条件阻止该对在开始时被使用。 

删除单个任意块的自由并不要求我们将任意删除放入轮廓状态。 假设最优解单独移除了一个被阻塞的块 (p)，而另一个块 (q) 仍然阻塞 (p)。 删除 (p) 并不是使 (q) 可用所必需的，因为 (p) 本身就是阻塞 (q) 的部分之一。 任何涉及与此依赖性无关的片段的操作都可以按相同的顺序执行，而无需 (p)。 我们可以推迟 (p) 的单次移除，直到 (p) 达到暴露的轮廓，并支付完全相同的金额。 因此，总是存在一个最佳解决方案，其中当该块位于当前轮廓上时，每次移除都会发生。 

## 方法

 自然的暴力解决方案将每个剩余的部分视为一个状态。 从一个状态开始，它可以尝试将每个当前暴露的白色棋子与每个当前暴露的黑色棋子一起尝试，也可以尝试删除每个棋子。 记忆化将使这成为 (m) 个片段上的 DP 子集。 即使忽略检查哪些部分被暴露的成本，状态空间也是 (2^m)，并且检查每个状态的所有可能对的成本 (O(m^2))。 对于 (m=144)，给出的上限为

 [
 2^{144}\cdot144^2\约4.6\times10^{47}
 ]

 配对状态检查。 蛮力在概念上是正确的，因为它直接对每个合法操作进行建模，但状态表示包含太多信息。 

有用的观察是几何的。 目前暴露的作品总是位于从左上角到右下角的单调楼梯上。 一旦该楼梯左下角的所有东西都被移除，楼梯上的任何部分都可以被移除，移除后楼梯将穿过该单元格。 

用恰好包含 (n) 向下移动和 (n) 向右移动的路径来表示楼梯。 将向下移动编码为 (0)，将向右移动编码为 (1)。 正好有

 [
 \binom{2n}{n}
 ]

 这样的路径。 局部图案 (01) 是楼梯的一角。 该角落的单元格正是当前可以移除的单元格。 删除该单元格会将本地路径从 (01) 更改为 (10)。 

空角不需要任何成本，只需将轮廓移动通过空单元即可。 被占用的角落可以单独移除，并支付其价值。 如果两个被占用的角有不同的颜色，则两块同时暴露，因此可以将它们一起删除，并可以立即进行两个相应的（01\to10）更改。 他们的转变成本是他们价值观的绝对差。 

这给出了所有轮廓状态上的最短路径式DP。 重要的简化是每次转换都会沿一个方向移动轮廓，因此状态形成 DAG。 不需要一般的最短路径算法。 我们可以按拓扑顺序处理掩模。 

轮廓方法有 (\binom{2n}{n}) 个状态。 对于一种状态，最多有 (n) 个角点，尝试所有角点对的成本为 (O(n^2))。 这给出了可接受的 (O(n^2\binom{2n}{n})) 复杂度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集 DP | (O(2^{n^2}n^4)) | (O(2^{n^2})) | 太慢了 |
 | 轮廓 DP | (O(n^2\binom{2n}{n})) | (O(2^{2n})) | 已接受 |

 ## 算法演练

 1. 用长度为 (2n) 的二进制字符串表示轮廓。 零表示轮廓向下移动，一表示轮廓向右移动。 恰好 (n) 位为 1，因此每个有效轮廓对应于 (\binom{2n}{n}) 个掩码之一。

我们使用轮廓将已清除的单元格与可能仍包含碎片的单元格分开。 图案 (01) 代表的角标识下一个可以曝光的单元格。 
2. 从向下 (n) 次然后向右 (n) 次的轮廓开始。 按照原始位顺序，这是 (0^n1^n)。 它唯一相关的角是棋盘的左下边界，正是第一个最初暴露的棋子必须出现的地方。 

最终轮廓为(1^n0^n)。 至此，整个电路板已完成处理。 
3. 对于每个轮廓，找到包含局部图案 (01) 的所有位置。 将每个此类位置转换为其板单元 ((x,y))。 还包括空单元格，因为轮廓可以零成本穿过它们。 
4. 对于每个角单元，执行一次移除过渡。 如果单元格为空，则添加的成本为零。 如果它包含一块，则增加的成本就是它的价值。 

这种转变表示在暴露时单独移除该部分，或者简单地通过空单元推进轮廓。 
5. 收集所有被占用的角落单元格。 对于具有不同颜色的每一对，执行同时将两个 (01) 角翻转到 (10) 的过渡。 添加它们值的绝对差。 

两个部分同时合法，因为它们在过渡之前是同一轮廓的两个角。 由于两个 (01) 图案不能重叠，因此两个局部翻转是独立的。 
6. 存储每个轮廓的最小成本。 过渡总是将 (01) 变为 (10)，因此它会将轮廓单调地移向最终轮廓。 这给出了一个 DAG，让我们可以按顺序处理状态，而无需重新访问它们。 
7. 实现时，反转轮廓位顺序。 然后原来的 (01\to10) 转换变成 (10\to01)，这增加了掩码的整数值。 因此，我们可以使用 Gosper 的组合生成技巧以递增的数字顺序枚举具有恰好 (n) 个设置位的所有掩码。 生成的掩模正是轮廓状态，但现在它们的过渡方向与枚举方向一致。 
8. 答案是最终轮廓反转形式的 DP 值。 空板自然也可以工作，因为通过空单元的每个轮廓过渡成本为零。 

工作原理：保持轮廓的 DP 值是清除该轮廓已处理一侧的所有内容，同时保持其余部分不变的不变式。 每个合法的操作都可以转化为当其棋子到达轮廓时执行的操作。 单个操作对应于一个角翻转，而有效的白黑对对应于同时进行的两个角翻转。 相反，DP 生成的每个转换都是合法操作，因为其角单元暴露在当前轮廓上。 因此，每个有效的移除序列都由通过 DP 的路径表示，并且每个 DP 路径都描述了具有完全相同成本的有效移除序列。 因此，在最终轮廓处取最小 DP 值即可得到最佳值。 

## Python 解决方案```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    n = int(input())

    board = [input().strip() for _ in range(n)]
    color = [[0] * n for _ in range(n)]

    for i in range(n):
        for j in range(n):
            if board[i][j] == 'W':
                color[i][j] = 1
            elif board[i][j] == 'B':
                color[i][j] = 2

    weight = []
    for _ in range(n):
        weight.append(list(map(int, input().split())))

    length = 2 * n
    size = 1 << length

    # We store the contour in reversed bit order.
    #
    # Original start:  0^n 1^n
    # Reversed start:  1^n 0^n
    #
    # Original end:    1^n 0^n
    # Reversed end:    0^n 1^n
    start = (1 << n) - 1
    end = start << n

    # int32 is sufficient:
    # at most 144 single removals, each <= 1e6.
    dp = array('i', [-1]) * size
    dp[start] = 0

    # Bit j of r is the lower bit of an original 01 corner.
    corner_mask = (1 << (length - 1)) - 1

    r = start
    limit = 1 << length

    while r < limit:
        cur = dp[r]

        if cur != -1:
            corners = r & ~(r >> 1) & corner_mask

            pieces = []

            c = corners
            while c:
                low = c & -c
                j = low.bit_length() - 1

                # In the reversed contour, this corner corresponds
                # to original bit positions i and i+1.
                i = length - 2 - j

                # Bits strictly above j+1 in the reversed mask
                # correspond to the original prefix before i.
                y = (r >> (j + 2)).bit_count()
                x = i - y

                col = color[x][y]

                if col:
                    pieces.append((j, col, weight[x][y]))
                    add = weight[x][y]
                else:
                    add = 0

                # 10 -> 01 in the reversed mask.
                # This increases the mask by exactly 2^j.
                nxt = r + low
                nv = cur + add

                old = dp[nxt]
                if old == -1 or nv < old:
                    dp[nxt] = nv

                c -= low

            # Remove two exposed pieces together.
            m = len(pieces)
            for a in range(m):
                j1, c1, w1 = pieces[a]
                for b in range(a):
                    j2, c2, w2 = pieces[b]

                    if c1 == c2:
                        continue

                    low1 = 1 << j1
                    low2 = 1 << j2

                    nxt = r + low1 + low2
                    nv = cur + abs(w1 - w2)

                    old = dp[nxt]
                    if old == -1 or nv < old:
                        dp[nxt] = nv

        # Gosper's hack: next mask with exactly n set bits.
        low = r & -r
        nxt = r + low
        r = (((nxt ^ r) >> 2) // low) | nxt

    print(dp[end])

if __name__ == "__main__":
    solve()
```输入首先被转换为两个数组。`color[i][j]`空单元格存储 0，白色单元格存储 1，黑色单元格存储 2。 分开的`weight`数组存储移除值。 

DP 数组通过以下方式使用有符号 32 位整数`array('i')`。 最大可能的答案最多是 (144\cdot10^6=144,000,000)，因此 32 位就足够了。 使用普通的 Python 列表会更昂贵，因为每个整数都是一个 Python 对象。 在 (n=12) 时，密集 DP 有 (2^{24}) 个条目，因此紧凑整数数组使内存消耗保持在 64 MB 左右。 

该实现向后存储轮廓。 在原始表示中，删除暴露的角会发生变化`01`到`10`，减少整数掩码。 处理递减掩码是可行的，但在 Python 中有效枚举所有此类掩码不太方便。 颠倒位顺序后，相同的转换变为`10`到`01`并增加掩模。 然后，Gosper 的 hack 按升序精确枚举包含 (n) 个掩码。 

对于位位置处的倒转角`j`，对应的原始角点出现在`i = 2*n - 2 - j`。 该角之前的原始右移动次数就是上面反转后缀中设置的位数`j + 1`，计算公式为```
y = (r >> (j + 2)).bit_count()
```向下移动的次数是`x = i - y`。 这就是为什么每个状态都不需要显式的 (2n) 步路径扫描。 

表达式```
corners = r & ~(r >> 1) & corner_mask
```找到每一个相反的`10`图案。 这`corner_mask`删除不存在的最终位置，避免在位 (2n-1) 处出现出界角点。 

对于一个角落，改变`10`到`01`将掩码精确增加 (2^j)，因此`nxt = r + low`就足够了。 两个不同的角不能重叠，因为两个`10`模式不能共享一点，因此两个翻转可以类似地写为`r + low1 + low2`。 

仅当两个角颜色不同时才考虑对过渡。 转移成本正好是`abs(w1 - w2)`，匹配配对删除规则。 每个角（包括空角）都考虑单个过渡，因为空轮廓单元必须是可遍历的，即使它表示没有删除。

 ### 示例 1

 对于官方样本，每个被占用的单元格都具有值（1），因此每个合法对的成本为零。 唯一的积极成本来自于在实现所需的配对之前必须单独移除的部件。 给定的最佳序列具有三个这样的删除。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O(n^2\binom{2n}{n})) | 每个轮廓有 (\binom{2n}{n}) 个轮廓，最多 (n) 个角点，并且有 (O(n^2)) 个角点对。 |
 | 空间| (O(2^{2n})) | 密集 DP 数组有 (2^{2n}) 个 32 位条目。 |

 在 (n=12) 时，轮廓状态的数量为

 [
 \binom{24}{12}=2,704,156。 
]

 DP 数组有 (2^{24}=16,777,216) 个条目，需要大约 64 MB 的 32 位整数。 理论时间界限是该问题的标准轮廓-DP 界限。 Python 实现还通过仅枚举恰好具有 (12) 个设置位的掩码来避免扫描所有 (2^{24}) 整数，这将处理状态的数量从约 1680 万个减少到约 270 万个。

 |`2 / W. / B.`两个值都是 1 | 2 | 当一个块阻挡另一个块时，相等的值并不意味着自由对 |
 |`2 / WB / B.`值为 5 和 7 | 9 | 一对仅在较早的单个移除后才可用 |

 ## 边缘情况

 一体式外壳```
1
W
7
```以唯一的轮廓过渡开始和结束。 该单元格是一个被占用的角点，因此 DP 添加 (7)，移动到最终轮廓，然后返回 (7)。 对于颜色或缺少的相反颜色，没有特殊情况代码。 

零成本对```
2
W.
.B
5 0
0 5
```首先穿过空的左下角。 这会暴露两个被占用的角落，一白一黑。 对转换将两个角翻转在一起并相加 (|5-5|=0)。 剩余的轮廓运动以零成本穿过空单元格，因此最终答案是（0）。 

阻塞案例```
2
W.
B.
1 0
1 0
```仅从占据角上的左下黑色棋子开始。 对于(1)，DP 必须单独将其删除。 然后白色部分暴露出来并单独去除以获得另一个（1），得到（2）。 没有将它们配对的过渡，因为它们在两个同时的角上永远不会有不同的颜色。 

更有趣的阻塞示例```
2
WB
B.
5 7
7 0
```从暴露的左下角黑色部分开始。 单独移除它需要花费 (7)。 然后轮廓达到第一行的两个块都是角的状态。 它们具有不同的颜色，因此 DP 可以将它们配对为 (|5-7|=2)。 总数为（9）。 这正是导致贪婪配对变得不可靠的依赖关系。 

最后，最大尺寸稀疏情况有 (n=12)，但只有一块。 轮廓 DP 仍然枚举完整的轮廓状态系列，但除了通过占用单元的转换之外，每个可到达的转换成本为零。 唯一的积极贡献是单次移除价值 (1,000,000) 的白色棋子，因此答案是 (1,000,000)。 测试证实该实现可以处理完整的 24 位轮廓表示和大单元值，而不会出现整数溢出。
