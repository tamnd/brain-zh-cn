 ## 解决方案
 ## 问题理解

 我们得到了一组不同的正整数，我们希望选择尽可能多的整数，同时避免特定类型的禁止关系。 这个限制很简单，但是是全局性的：在所选择的子集中，我们不允许有两个数字，其中一个恰好是另一个乘以固定整数 k。 

另一种看待它的方式是每个数字 x “阻塞”数字 x·k。 如果两者都出现在我们选择的集合中，则违反了条件。 任务是选择不存在此类阻塞对的最大可能子集。 

输入大小最多允许 100,000 个数字，每个数字可能大到 10^9。 这立即排除了任何比较所有对或以非结构化方式重复检查整除关系的方法。 在最坏的情况下，对所有对进行二次检查将涉及 10^10 次比较，这远远超出了时间限制。 

任意选择数字的天真贪婪方法也会失败。 例如，如果 k = 2 并且数组为 [2, 3, 4, 8]，则首先选择 2 会迫使我们拒绝 4，但先选择 3 是无害的，并且允许稍后考虑 4 和 8。 这表明没有结构的局部决策会减少最终答案。 

当链条长度超过长度二时，会出现另一个微妙的故障情况。 对于 k = 2 和数字 [1, 2, 4, 8]，如果我们不仔细处理依赖关系，在没有策略的情况下选择最小或最大可能会错误地删除太多有用的元素。 

关键的困难在于每个数字仅与其 k 的倍数相互作用，形成独立的链，而不是整个集合中的任意关系。 

## 方法

 如果我们考虑有向关系，问题的结构就会变得更加清晰。 每个数x只能影响x·k，不存在其他相互作用。 这意味着整个集合分解为 x、x·k、x·k^2 等形式的独立链。 

在每个这样的链中，我们必须选择一个没有相邻元素的子集。 这减少了在边连接连续多个节点的路径中选择尽可能多的节点。 类路径依赖中的最佳选择是获取每个元素，除非受到邻接约束强制，但这里有一个更简单的结构：由于所有值都是不同的并且沿着链严格递增，因此我们可以从最大到最小贪婪地处理。 

如果我们按降序对数组进行排序，我们可以决定每个数字是否应该包含在内。 当我们考虑一个值x时，如果x·k存在并且已经被选择，那么x必须被排除。 否则，我们包括 x。 按降序处理可确保如果存在倍数，则在其除数之前对其进行处理，这使得依赖项检查在本地且已解决。 

这是可行的，因为每个禁止对都是通过乘以 k 从小到大定向的，因此较大的元素总是决定较小的元素的命运。 

强力方法将尝试所有子集，或者至少检查每个候选子集的兼容性，从而导致指数或二次行为。 贪婪排序在排序后将其折叠为一次传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) 或 O(n^2) | O(n) | 太慢了 |
 | 最优贪心 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

1. 将所有数字按降序排列。 这确保了每当我们处理一个数字时，它的所有倍数（如果它们存在于输入中）都已被处理。 
2. 维护一个哈希集，用于存储我们决定包含在子集中的所有数字。 
3. 按排序顺序迭代每个数字 x。 
4. 对于每个 x，检查 x·k 是否已在所选集合中。 如果是，请跳过 x，因为包含它会与已选择的倍数创建禁止对。 
5. 如果 x·k 不在集合中，则将 x 包含在答案中并将其插入集合中。 
6. 处理完所有数字后，所选集合的大小就是答案。 

这样做的原因是每个约束都是单向的：如果已经选择了 x·k，则仅禁止 x。 由于我们首先处理较大的值，因此任何潜在的冲突都会在到达较小的元素之前决定，并且后面的操作不会使之前的决定无效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))

    arr.sort(reverse=True)
    chosen = set()

    ans = 0

    for x in arr:
        if x * k in chosen:
            continue
        chosen.add(x)
        ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```排序步骤至关重要，因为它强制执行正确的处理顺序。 如果没有降序，我们可能会先接受一个小数字，然后通过添加其倍数来错误地阻止它，从而违反了贪婪的正确性。 

哈希集为 x·k 提供恒定时间的成员资格检查，这对于保持在时间限制内至关重要。

 ## 边缘情况

 当 k 等于 1 时，会出现临界边缘情况。在这种情况下，每个数字 x 都会通过 x·1 = x 与自身发生冲突，但由于输入保证不同的值，因此没有任何对实际上违反了规则。 该算法自然地处理这个问题，因为 x·k 始终是 x，在插入之前不在集合中，因此所有元素都被接受。 

另一种边缘情况是纯指数链，如 1、k、k^2、k^3。 按降序处理意味着我们首先遇到 k^3，将其包含在内，并且仅当包含其倍数时才逐步拒绝较低的元素。 这确保我们永远不会意外地选择链中的两个相邻元素。 

第三种情况是多个独立链在数字上重叠但在结构上不重叠，例如 k = 3 的 [2, 3, 4, 9, 18]。该算法正确地分离了依赖关系，因为每个数字只检查单个乘法关系，避免了不相关链之间的干扰。
