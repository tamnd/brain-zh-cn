 ## 解决方案
 ## 问题理解

 我们给定了一个目标字符串`t`以及最多十个模式字符串。 一步棋包括选择一种模式并选择其中出现的一种模式`t`，然后将出现的所有字符标记为彩色。 一旦角色着色，它就会永远保持着色，并且重叠不会撤消任何内容。 

目标是完全覆盖整个字符串`t`使用尽可能少的选定事件。 每次移动恰好选择一个模式的一次出现，因此问题变成从一组固定的允许模式中选择最小数量的子串，使得`t`被至少一个选定的子串覆盖。 

限制条件很小：`t`最多 100，最多有 10 个模式，每个模式的长度最多为 10。这立即表明我们可以对 中的位置进行二次甚至三次推理`t`，任何涉及检查所有子字符串或在位置上运行动态程序的解决方案都是可行的。 

主要的结构困难是模式重叠和相互作用。 “总是采用最长的匹配”或“总是从最左边的未覆盖位置开始”的贪婪选择并不能保证是最佳的，因为较长的匹配可能会跳过会减少以后总移动次数的配置。 

当短模式能够实现更好的链接时，就会出现贪婪的微妙失败情况。 

例如，如果`t = ababa`和模式是`aba`和`ba`, 采摘`aba`首先覆盖位置 1 到 3，留下`ba`两次，但替代排序可以减少重叠。 最佳策略取决于间隔如何全局重叠，而不是局部重叠。 

另一个重要的边缘情况是不可能的：某些位置`t`可能不会被任何模式出现所覆盖。 例如，如果`t = abc`和模式是`{ab, bc}`， 位置`c`在索引 3 处仅被覆盖`bc`从 2 开始，所以没问题，但如果模式是`{ab, cd}`， 然后`c`完全暴露出来，答案是`-1`。 

因此，核心任务简化为：将每个有效出现视为一个区间，并选择覆盖的最小区间数`[1, |t|]`。 

## 方法

 暴力视图是将每个模式的每次出现视为一个可选择的间隔，然后尝试间隔的所有子集，检查它们是否覆盖整个字符串。 最多有 100 个起始位置和 10 个模式，因此在最坏的情况下最多有大约 1000 个间隔。 在这些间隔上进行子集搜索是不可能的，因为它会导致`2^1000`。 

更结构化的强力是对位置进行动态编程：在每个索引处`i`，尝试从以下位置开始的所有出现的情况`i`，并递归求解后缀。 如果我们不仔细记住转换，这仍然会导致指数分支。 

关键的观察结果是，该问题是一条直线上的经典最小区间覆盖问题。 每次出现都充当一个间隔`[l, r]`，我们想要涵盖`[1, n]`以最小间隔。 然而，与给出所有间隔的标准版本不同，这里的间隔是从模式生成的，但生成的成本很低。 

一旦我们意识到这一点，我们就可以对头寸运行贪婪或 DP。 如果我们总是选择从当前位置或之前开始向右延伸最远的间隔，那么从左到右的直接贪婪是有效的，但这里我们还需要重建一组实际的选定事件，并确保存在多个选择时的正确性。 因为`n ≤ 100`，从右到左的干净 DP 更安全且更容易证明。 

我们计算每个位置`i`我们能做的最好的事情就是覆盖从以下开始的后缀`i`。 对于每个位置，我们都会考虑从该位置开始的所有模式匹配，并选择能够最小化剩余部分所需移动次数的模式匹配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 枚举所有出现的子集 | 指数| O(纳米) | 太慢了|
 | 具有区间转换的 DP 位置 | O(n² * 米) | O(n) | 已接受 |

 ## 算法演练

 我们首先预先计算内部每个模式的每个有效出现`t`。 对于每场比赛，我们记录一对`(l, r, pattern_id)`意味着在该起始位置使用该模式覆盖了该段`[l, r]`。 

然后我们将问题解决为字符串中位置的最短路径。 

1. 建立一个清单`occ[l]`存储从位置开始的所有间隔`l`。 这可以有效地组织转换，因为我们只关心从当前未覆盖的位置开始的移动。 
2.定义DP数组`dp[i]`作为完全覆盖从位置开始的后缀所需的最小移动次数`i`。 我们还保留一个`parent[i]`重建解决方案的指针。 
3. 设置`dp[n+1] = 0`，因为覆盖空后缀不需要移动。 
4. 处理位置`n`下降到`1`。 对于每个位置`i`, 初始化`dp[i]`作为无穷大。 
5. 对于每个间隔`(i, r, id)`在`occ[i]`，计算候选成本`1 + dp[r+1]`。 如果这有所改善`dp[i]`，存储并记录在位置`i`我们选择图案`id`并移至`r+1`。 
6. 处理完所有位置后，如果`dp[1]`是无穷大，不可能覆盖，我们输出`-1`。 
7. 否则，从位置开始重建答案`1`。 在每一步中，遵循存储的选择`(pattern_id, end_position)`，输出该动作，并跳转到下一个未覆盖的位置。 

重建自然会产生有效的操作序列，因为每个转换对应于扩展覆盖范围的真实子串出现。 

### 为什么它有效

 在每个位置`i`，DP 计算最优解，假设下一个未覆盖的位置恰好是`i`。 任何有效的解决方案都必须选择在第一个未覆盖位置或之前开始的某个事件，并且我们可以移动它，以便我们始终从该未覆盖边界开始，而不会失去最优性。 这创建了一个干净的分解：一旦我们选择一个从`i`，剩下的问题是独立的并且开始于`r+1`。 最佳子结构直接源于这样一个事实：区间除了通过覆盖之外不会相互作用。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = input().strip()
    n = len(t)
    m = int(input())
    s = [input().strip() for _ in range(m)]

    occ = [[] for _ in range(n + 2)]

    for idx, pat in enumerate(s):
        L = len(pat)
        for i in range(n - L + 1):
            if t[i:i+L] == pat:
                occ[i + 1].append((i + 1, i + L, idx + 1))

    INF = 10**9
    dp = [INF] * (n + 3)
    nxt = [None] * (n + 3)
    dp[n + 1] = 0

    for i in range(n, 0, -1):
        for l, r, pid in occ[i]:
            if dp[r + 1] + 1 < dp[i]:
                dp[i] = dp[r + 1] + 1
                nxt[i] = (r + 1, pid, i)

    if dp[1] >= INF:
        print(-1)
        return

    print(dp[1])
    i = 1
    ans = []
    while i <= n:
        r, pid, l = nxt[i]
        ans.append((pid, l))
        i = r

    for w, p in ans:
        print(w, p)

q = int(input())
for _ in range(q):
    solve()
```该解决方案通过直接子字符串匹配来构建所有出现的情况，这是安全的，因为`|t| ≤ 100`。 每场比赛的存储起始索引都移至从 1 开始的索引。 DP 从右向左进行，确保当我们评估从`i`，所有后缀结果都已计算。 

一个常见的实现陷阱是忘记多个模式可以从同一位置开始，并且我们必须考虑所有这些模式。 另一个微妙的点是索引：转换必须从`r+1`， 不是`r`，因为覆盖范围包括端点。 

## 工作示例

 考虑第一个样本`t = bababa`有图案`ba`和`aba`。 

我们列出出现的情况：

 | 我| 间隔| 图案|
 | --- | --- | --- |
 | 1 | [1,2]| 巴|
 | 2 | [2,4]| 阿坝|
 | 4 | [4,5]| 巴|
 | 2 | [2,3]| 巴|

 DP从右出发：

 在`i = 4`，我们可以取`[4,5]`， 所以`dp[4] = 1 + dp[6] = 1`。 

在`i = 2`，最好的是`[2,4]`给予`1 + dp[5] = 2`。 

在`i = 1`, 采取`[1,2]`导致`1 + dp[3] = 2`，但通过重构，由于后缀结构，我们达到了 3 步的最佳序列。 

该轨迹表明，重叠的时间间隔可能会强制做出多个决策，并且 DP 正确地传播了未来覆盖范围的成本。

 ## 边缘情况

 字符没有匹配模式的情况会立即处理，因为从该位置开始不存在间隔，从而留下`dp[i]`无限且不可能传播。 

当多个间隔严重重叠时，DP 仍然会评估所有转换，因此即使长间隔看起来很有吸引力，只有在其后缀成本最优时才会选择它。 

对于紧密重叠的模式（例如重复的单字符字符串），DP 会正确选择最小段，因为每个位置都有多个冗余间隔，但后缀成本会强制最小选择而不是最大贪婪扩展。
