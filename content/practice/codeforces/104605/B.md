 ## 解决方案
 ## 问题理解

 我们给出了 knedlíky 的目标数量$N$。 餐厅分为三种类型：有的给 4 knedlíky，有的给 5 knedlíky，有的给 6 knedlíky。我们可以为每种类型选择几家餐厅，但不能超过可用数量$A, B, C$。 每个餐厅最多只能使用一次。 

问题是我们是否可以选择一些数字$x, y, z$这样：$$4x + 5y + 6z = N$$和$0 \le x \le A$,$0 \le y \le B$,$0 \le z \le C$。 

每个测试用例都是独立的，我们必须回答这样的选择是否存在。 

约束条件很大：最多$10^5$测试用例和值高达$10^8$。 这排除了任何尝试探索所有组合的方法$x, y, z$或执行动态规划$N$。 任何解决方案都必须将每个测试用例减少到恒定或非常小的有界工作。 

天真的尝试会尝试所有三元组$(x,y,z)$在范围内，但最坏的情况允许$10^8$每个变量的可能性，这是完全不可行的。 

一种更微妙的失败模式来自贪婪推理。 例如，总是采用尽可能多的 6-knedlík 餐厅可能会破坏有效的解决方案。 如果$N = 20$，贪婪会占用三个 6 (18)，剩下 2，这是不可能的，即使存在有效的解决方案：$5 + 5 + 5 + 5$。 

核心困难在于，硬币尺寸 4、5 和 6 在有界计数下会发生非平凡的相互作用，因此我们需要一种结构化的方法来仅探索恒定数量的有意义的配置。 

## 方法

 暴力解决方案将迭代所有有效的$x, y, z$，检查方程是否成立。 这是正确的，但由于立方搜索空间而立即失败。 

关键的观察结果是硬币尺寸很小并且实际上是连续的。 一旦我们有足够的灵活性，可表示和的集合就会变得密集。 事实上，对于硬币 4、5 和 6，唯一无法达到的无限值是非常小的例外，例如 1、2、3 和 7。除此之外，还存在大量组合。 

剩下的复杂性是上限$A, B, C$。 然而，由于每个变量都可以在保留结构的块中移动，因此可以通过仅检查候选的一个小邻域来找到任何有效的解决方案（如果存在）$(y, z)$价值观。 一次$y$和$z$是固定的，$x$是唯一确定的：$$x = \frac{N - 5y - 6z}{4}$$所以任务减少到尝试恒定数量的小$y, z$涵盖所有必要的残基和边界配置的候选者。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 全力暴力破解$x,y,z$|$O(ABC)$|$O(1)$| 太慢了 |
 | 不断进行邻里搜索$y,z$|$O(1)$每次测试|$O(1)$| 已接受 |

 ## 算法演练

 我们将每个测试用例减少为检查恒定数量的结构化候选者。 

### 1. 处理琐碎的不可能的事情

 我们首先观察到一些小值$N$根本不能用 4、5 和 6 组成。它们是：$$N \in \{1, 2, 3, 7\}$$对于这些情况，无论边界如何，都不存在组合。 

### 2. 枚举小候选$y$和$z$我们尝试所有的小值$y$和$z$，通常在 0 到 5 的范围内。这样做的原因是，任何较大的值都可以被视为在变量之间转移质量，而不会从根本上改变可表示性，因为 4、5 和 6 的差异可以通过调整其他变量来补偿。 

这将搜索空间减少到最多 36 对。 

### 3. 验证每个候选人

 对于每对$(y, z)$，我们计算：$$rem = N - 5y - 6z$$如果$rem < 0$，这对无效。 

我们还要求：$$rem \bmod 4 = 0$$然后：$$x = rem / 4$$最后，我们检查：$$x \le A,\quad y \le B,\quad z \le C$$如果满足所有约束，则答案为“是”。 

### 为什么它有效

 关键属性是任何可行的解决方案都可以转化为其中的解决方案$y$和$z$位于有界区域而不失去有效性，因为增加$y$或者$z$by 4 保留剩余总和中可被 4 整除的能力并进行调整$x$可以预见的。 由于我们只关心存在，探索这些等价类的代表就足够了。 有界枚举保证我们至少命中任何有效配置的一个代表。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    bad = {1, 2, 3, 7}

    for _ in range(T):
        N, A, B, C = map(int, input().split())

        if N in bad:
            print("NO")
            continue

        ok = False

        for y in range(6):
            for z in range(6):
                val = 5 * y + 6 * z
                rem = N - val
                if rem < 0:
                    continue
                if rem % 4 != 0:
                    continue
                x = rem // 4
                if x < 0:
                    continue
                if x <= A and y <= B and z <= C:
                    ok = True
                    break
            if ok:
                break

        print("SI" if ok else "NO")

if __name__ == "__main__":
    solve()
```该解决方案在恒定网格上迭代$(y, z)$价值观。 嵌套循环故意很小，这样即使$10^5$测试用例中，总工作量在实践中保持线性。 

可除性检查确保导出的正确性$x$。 边界检查强制限制任何餐厅类型都不会被过度使用。

 ## 边缘情况

 一个微妙的情况是当$N = 0$。 该算法正确地接受了这一点，因为选择$x = y = z = 0$总是满足方程，并且边界也允许它。 

另一个边缘情况是当$N$很小但不在显式不可能集中，例如$N = 4$。 该算法发现$x=1, y=z=0$，这是有效的并且遵守界限，如果$A \ge 1$。 

更危险的情况是存在有效的表示但需要在硬币类型之间转移权重，例如：$$N = 20, A = 0, B = 4, C = 0$$这里只允许5s，所以算法必须正确识别$4 \times 5 = 20$。 这是因为枚举包括$y=4, z=0$在有界检查中。
