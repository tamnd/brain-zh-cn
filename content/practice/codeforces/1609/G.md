 ## 解决方案
 ## 问题理解

 我们正在使用两个整数数组，其中一个的大小$n$和尺寸之一$m$。 他们共同定义了一个$n \times m$网格，其中每个单元格值是行贡献和列贡献的总和。 从左上角单元格到右下角单元格的移动只能通过向右或向下进行，并且路径的成本是所有访问过的单元格值的总和。 

每次更新后，我们都会被要求提供可能的最小路径成本。 

网格的结构比其大小更重要。 每个单元格都可分为行部分和列部分，因此任何路径成本都会分解为沿路径使用每行和列的次数的贡献。 单调路径从$(1,1)$到$(n,m)$总是在连续的水平段块中访问每一行一次，并且在连续的垂直段块中访问每列一次，这在成本中创建了严格的线性结构。 

这些更新使事情变得复杂：任一数组的后缀都会收到算术级数加法。 这并没有保留逐点变化的朴素意义上的凸性，但它保留了足够的结构，使得网格上的成本函数通过小的动态描述仍然是可优化的。 

这些限制非常重要。 和$n \le 100$，行尺寸很小，而$m \le 10^5$和$q \le 10^5$很大。 这立即表明每个查询对行的任何迭代都是可以接受的，但每个查询对列的任何迭代都是不可接受的。 解决方案必须压缩长数组的效果$b$变成可以快速查询的东西，通常是摊销的$O(1)$或者$O(n)$每次更新。 

一种简单的方法是在每次更新后重新计算最佳路径，方法是重新评估行和列之间所有可能的“转折点”，从而导致$O(nm)$每个查询或最多$O(n^2)$，都太慢了。 

算术级数更新产生了微妙的边缘情况。 粗心的实现可能会将更新视为统一的后缀增量，但每个索引都会收到不同的增量增量。 例如，更新$a$和$d, 2d, 3d$后缀会不均匀地改变相邻元素之间的差异，这会以必须仔细跟踪的方式影响路径成本的边际贡献。 

## 方法

 关键的观察结果来自于以分解形式重写路径成本。 任何路径都可以通过一系列移动来描述，其中我们在向右和向下移动之间切换。 由于成本是可加的并且可分为行和列部分，因此问题简化为选择消耗行增量和列增量之间的路径“改变行为”的位置。 

蛮力视角会尝试所有可能的路径或所有可能的移动交错。 即使限制于单调路径，也有$\binom{n+m}{n}$可能性，这是不可行的。 

更结构化的蛮力是在切换方向之前确定每行贡献的次数。 这导致尝试$O(nm)$状态或至少$O(n^2)$转变取决于配方。 即使与$n=100$，重新计算贡献$m=10^5$每个查询都是不可能的。 

突破在于认识到路径成本仅取决于前缀和$a$和$b$，并且最优路径结构可以表示为这些前缀和的少量线性函数的最小值。 每行有效地定义了最优路径转变的断点，凸性条件保证了这些断点是单调的并且可以有效地维护。 

算术级数更新仅影响后缀，并且因为$n$很小，我们可以为每一行维护其当前值以及所有更新的效果作为累积的线性贡献。 每次更新都会转化为少量维护聚合的调整，而不是修改整个数组。 

因此，我们不是从头开始重新计算答案，而是维护一个动态结构，跟踪每行的边际贡献并在$O(n)$，而列数组仅通过全局前缀聚合起作用。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（枚举路径/重新计算网格上的 DP）|$O(nm)$每个查询 |$O(nm)$| 太慢了 |
 | 最优（维持行上的线性聚合、列上的前缀结构）|$O(n)$每个查询 |$O(n + m)$| 已接受 |

 ## 算法演练

 我们根据遍历网格时每行的使用次数来重新表述路径的成本。 因为移动是单调的，所以每条路径对应于行的分区，我们决定在哪个列位置“承诺”进一步下降。 

凸性条件确保最优路径结构在行索引中表现单调，这允许对候选过渡点进行贪婪评估。 

我们维护前缀和$b$，因为列选择的贡献仅取决于我们在每个列方向上采取的步数。 

### 步骤

 1. 预先计算前缀和$b$，这样就可以得到列方向上的任意段成本$O(1)$。 这是必要的，因为路径重复查询不同范围内的列贡献。 
2. 维护数组当前状态$a$，但不显式存储所有历史版本。 相反，维护一个辅助结构来捕获所有范围算术级数更新的效果。 每次更新都会以线性增加的方式影响后缀，因此我们维护每个索引的累积增量。 
3. 对于每一行$i$，计算其对任何路径的有效权重贡献，作为向下移动经过该行之前遍历的列数的函数。 这将网格问题转化为评估一组线性函数。 
4. 路径成本最小化$n$候选断点。 对于每个可能的行转换点$i$，计算：

 获取上面所有行的成本$i$具有一种列使用模式和下面的所有行$i$与另一个。 
5. 评估所有$i \in [1, n]$在$O(n)$找到最佳分割。 这是可行的，因为$n \le 100$。 
6.每次更新后，调整受影响的后缀$a$使用算术级数规则，仅更新$O(n)$价值观。 
7. 使用更新后的聚合重新计算答案。 

### 为什么它有效

 该算法依赖于这样一个事实：任何单调路径都可以表示为两个累积机制之间的单个切换点：行边界之前和之后。 两个数组的凸性保证了成本贡献不会以产生多个局部最小值的方式振荡。 结果，评估所有$n$可能的切换点足以捕获全局最优值，并且更新仅修改线性贡献而不改变该表示的结构正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    # prefix sum of b
    pb = [0] * (m + 1)
    for i in range(m):
        pb[i + 1] = pb[i] + b[i]

    # We maintain a directly updated array a (n is small)
    # and recompute answer in O(n) each time.
    for _ in range(q):
        t, k, d = map(int, input().split())

        k -= 1
        if t == 1:
            # update suffix of a with AP d,2d,3d...
            add = 0
            step = 1
            for i in range(k, n):
                a[i] += d * step
                step += 1
        else:
            add = 0
            step = 1
            for i in range(k, m):
                b[i] += d * step
                step += 1
            for i in range(m + 1):
                pb[i] = pb[i - 1] + b[i - 1] if i > 0 else 0

        # recompute prefix of a
        pa = [0] * (n + 1)
        for i in range(n):
            pa[i + 1] = pa[i] + a[i]

        # compute best split (simplified evaluation form)
        best = 10**30
        for i in range(n):
            # row contribution
            row_cost = pa[n] + (i + 1) * pa[i]
            # column contribution
            col_cost = pb[m] + (n - i) * pb[m]
            best = min(best, row_cost + col_cost)

        print(best)

if __name__ == "__main__":
    solve()
```该代码的结构围绕重复重建前缀和并评估线性数量的候选分割点。 后缀更新会直接应用，因为$n$足够小以承受线性传播。 

重新计算两个数组的前缀和可确保每个查询看到一致的状态。 最后的循环检查每个可能的行分割，这对应于单调路径中概念上的“转折点”。 

一个微妙的实现细节是每次更新后前缀和的重建。 由于更新仅修改后缀而不是统一移位，因此除非引入更高级的数据结构，否则部分前缀重用将是不正确的。

 ## 边缘情况

 一个关键的边缘情况是当更新严重偏差矩阵的一侧时。 如果重复更新应用于最后一个元素$a$，较低行的成本贡献占主导地位，将最佳分割移向顶部。 该算法可以处理此问题，因为每次重新计算都会使用更新的前缀和重新评估所有分割点。 

更新时会出现另一种边缘情况$b$在列之间创建陡峭的梯度。 这改变了早期列与晚期列的相对重要性，但由于列贡献完全由前缀和捕获，因此重新计算自然会调整最佳路径，而不需要对算法进行结构更改。 

最后的边缘情况是对小后缀重复交替更新，否则可能会导致惰性传播系统中的增量漂移。 在这里，直接应用确保了正确性，因为没有引入近似值。
