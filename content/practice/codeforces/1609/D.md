 ## 解决方案
 ## 问题理解

 我们有一群最初没有任何关系的人。 随着时间的推移，我们会看到一系列的配对，每对都代表一个最终必须满足的约束：配对中的两个人最终必须连接起来，这意味着存在一连串的直接介绍将他们联系起来。 

威廉是唯一被允许互相介绍人的人。 每个介绍都将两个以前未连接的个体联系起来，并有效地为最初为空的图添加一条边。 执行第一个 i 引入后，必须满足所有第一个 i 约束，这意味着这些对中的每一对必须位于结果图的相同连接组件中。 

对于每个前缀长度 i，我们概念上从头开始，执行精确的 i 引入，并确保满足前 i 个约束。 在选择这些介绍的所有有效方法中，我们希望最大化可通过介绍相互联系的最大群体的规模。 用图形术语来说，我们最大化最大连通分量的大小。 

关键的微妙之处在于每个前缀都是独立的。 我们不会继承以前前缀的任何结构，因此每个 i 在相同的 n 个节点上定义一个单独的优化问题，并且第一个 i 需要连接约束。 

约束足够小，n 最多 1000 允许 O(n^2) 或 O(n^2 log n) 推理。 然而，我们对每个前缀重新计算的事实强烈表明我们需要一个可以增量更新的结构，而不是每次都从头开始重新计算连接性。 

为每个 i 从头开始​​重建连接并尝试强制约束的简单方法将重复运行完整的图构造或搜索所有可能的引入。 这很快就变得不可行，因为即使检查每个前缀的可行性也已经需要大量的联合查找或 BFS 逻辑，并且对每个前缀独立执行此操作会将成本乘以 d。 

当约束形成重叠组件时，会出现常见的边缘情况。 例如，如果约束条件为(1,2)、(2,3)、(3,4)，则最优构造快速构建一条链，并且最大的分量稳定增长。 但是，如果约束在早期是不相交的，并且仅在稍后连接大组，则在没有仔细合并顺序的情况下对约束的贪婪局部解释可能会低估可实现的组件大小。 

另一个微妙的问题是误解了必须最大化的内容。 我们没有最大化满足的约束或添加的边的数量。 在强制执行前缀中的所有约束后，我们将最大化最大连接组件的大小。 

## 方法

 暴力视角首先观察到，对于固定的 i，我们必须确保 (x1, y1) 到 (xi, yi) 的所有对都位于同一连接组件中。 人们可以尝试通过重复添加边并检查有效性来构建图，但这会导致一个关键困难：只要所有约束都连接起来，我们就可以自由选择 William 执行哪些介绍。 

所以真正的结构是这样的：约束迫使某些节点组最终出现在同一个连接的组件中。 如果我们将前 i 个约束视为辅助图中的边，则任何有效的最终配置必须至少连接该辅助图的每个连通分量。 这意味着约束图的每个组件必须完全包含在 William 构建的图的某个连接组件内。 

最佳策略是认识到 William 应该以最小化碎片的方式连接组件，从而有效地允许我们将每个约束组件视为“必须合并”的块。 唯一的自由是如何使用恰好 i 个边来合并这些块。

关键的见解是，由于我们执行了 i 个引入，并且每个引入合并了两个组件，因此我们从 n 个独立节点开始并执行 i 个合并。 i 合并后，我们总是有 n - i 个组件。 因此，问题归结为控制这些合并的分布方式，同时遵守必须包含的约束组件。 

这导致了对约束的贪婪联合查找过程：我们逐一处理约束，将它们的端点联合起来。 i 个并集之后的并查找结构中最大连接组件的大小给出了最佳的可实现答案，因为任何有效的构造都必须至少尊重这些强制连接，并且我们始终可以实现精确实现这些合并的构造。 

因此，我们维护 DSU 并跟踪组件尺寸。 处理完每个约束后，我们更新最大 DSU 组件的大小。 

微妙的理由是约束只需要连接性，而不需要直接边缘，因此合并端点就足够了。 每个约束有效地强制其组件在任何有效实现中的联合。 一旦我们联合它们，我们就精确地捕获了最小的强制结构，并且由于我们可以在约束之外任意引入，所以我们总是可以实现最大组件等于由约束形成的最大 DSU 组件的配置。

 ## 算法演练

 我们增量处理约束，同时维护不相交的集合并集结构。 

1. 初始化具有 n 个节点的 DSU，每个节点都有自己的组件。 每个组件的尺寸为 1。 
2. 维护一个变量`best`它存储迄今为止看到的最大组件尺寸。 
3. 对于每个约束 i = 1 到 d，我们采用 (x_i, y_i) 对并合并它们的 DSU 分量。 如果它们已经在同一个组件中，则不会发生任何变化。 
4. 每次联合操作后，我们更新`best`以反映 DSU 当前存在的最大组件尺寸。 
5、输出`best`处理完每个前缀 i 后。 

其起作用的关键原因是每个约束都强制两个组之间的连接。 一旦两个组在约束中连接，任何有效的构造都必须确保它们在最终图中连接。 DSU 将所有此类强制关系压缩为组件，并且由于每次引入都合并两个组件，因此跟踪组件大小可以直接捕获最大可能连接组的增长。 

### 为什么它有效

 在任何前缀 i 处，约束边定义一个图，其连接组件是在每个有效构造中必须连接的人的等价类。 任何有效的引入计划都必须使每个类在内部相互连接，因此每个类的行为就像一个超级节点。 我们可以形成的最大可能的连接组件是通过将每个约束组件视为不可分并计算其大小来获得的。 DSU 准确地维护了这些等价类，并且由于合并是唯一允许的操作，因此 i 并集后的 DSU 状态表示满足前 i 个约束后可实现的最大强制连接结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return 0
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return self.size[a]

n, d = map(int, input().split())
dsu = DSU(n)

best = 1
out = []

for _ in range(d):
    x, y = map(int, input().split())
    x -= 1
    y -= 1
    merged_size = dsu.union(x, y)
    if merged_size:
        best = max(best, merged_size)
    out.append(str(best))

print("\n".join(out))
```DSU 结构跟踪由约束引起的连接组件。 每个联合对应于强制两个人必须最终处于同一个连接组中。 大小数组允许恒定时间跟踪每个结果组有多大，并更新`best`确保我们始终知道每个前缀之后可实现的最大簇。 

关键的实现细节是我们只更新`best`当合并真正发生时。 如果两个节点已经在同一个组件中，则约束不会添加新结构，并且答案保持不变。

 ## 边缘情况

 一个小但重要的情况是当约束重复已经连接的对时。 例如：

 输入：```
4 3
1 2
2 3
1 3
```经过前两个约束后，节点 {1,2,3} 已经统一。 第三个约束不改变 DSU 状态。 该算法正确地忽略了它，因为`union`返回 0 和`best`没有更新。 输出与没有强制执行新连接的事实保持一致。 

另一种情况是约束形成两个独立的集群，这些集群稍后才变得有用。 DSU 确保部分合并正确累积，并且仅在真正合并发生时才更新最大组件，从而防止冗余约束造成的通货膨胀。
