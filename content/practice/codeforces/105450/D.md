 ## 解决方案
 ## 问题理解

 我们在 2D 网格上得到一组点，我们从坐标 (0, 0) 处的原点开始。 我们要选择一个方向并沿着经过原点的直线行走。 当沿着那条线移动时，我们收集正好位于其上的所有糖果。 目标是选择穿过原点并包含最多给定点的线。 

每个糖果只是平面上的一个固定点。 唯一有效的线是那些经过原点的线，因此每个候选解完全由从 (0, 0) 到某个糖果点 (x, y) 的方向向量确定。 位于同一条线上的所有点都具有相同的斜率，或者更准确地说，具有相同的减小的方向比。 

输入大小高达 100,000 个点，这会立即排除比较每对点或检查所有对斜率的情况。 任何尝试 O(n²) 行为的解决方案在最坏的情况下都会执行多达 10^10 次比较，这远远超出了一秒内的可行限制。 这将我们推向 O(n log n) 或 O(n) 方法。 

一些微妙的情况在这里很重要。 首先，相对象限中的点可以位于通过原点的同一条线上，例如 (2, 3) 和 (-4, -6)。 除非仔细标准化，否则简单的斜率计算 y/x 会将它们视为不同的符号。 

其次，必须处理垂直线。 像 (0, 5) 这样的点定义了一条有效的线，但如果不单独处理，斜率表示将涉及除以零。 

第三，正常化至关重要。 如果不将方向向量简化为规范形式，则可以在不同的整数表示（例如 (2, 4) 和 (1, 2)）下对同一条线进行多次计数，必须将其视为相同。 

## 方法

 一个蛮力的想法是考虑每对点并计算通过原点的线和该对点的方向。 对于每条这样的线，我们可以通过叉积检查共线性来计算其上有多少个点。 这是有效的，因为两个点定义了一个方向，并且可以针对该方向测试所有其他点。 

然而，这会导致 O(n²) 个候选方向，并且对于每个方向，我们可能会扫描所有 n 个点，以最坏的形式给出 O(n³)，或者如果我们优化计数，则最多给出 O(n²)。 当 n = 10⁵ 时，甚至 O(n²) 也是不可能的。 

关键的观察是，通过原点的每条有效线都可以由从原点到该线上任何点的方向向量唯一表示。 我们不需要枚举点对，只需按其归一化方向对每个点进行分类即可。 共享相同简化方向的点位于同一条线上，因此任务简化为计算归一化方向向量的频率。 

这将问题转化为简化整数对上的散列问题。 每个点只贡献一个方向，我们维护一个频率图来找到最大计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n2) 到 O(n3) | O(1) | O(1) | 太慢了|
 | 方向散列| O(n log n) 或 O(n) | O(n) | 已接受 |

 ## 算法演练

1. 对于每个点 (x, y)，计算其距原点方向的归一化表示。 这确保了同一条线上的所有点都映射到相同的键。 归一化是必要的，因为像 y/x 这样的原始比率在整数缩放或符号变化下不稳定。 
2. 如果 x 为零，则将该方向视为特殊的垂直类。 所有 x = 0 的点都属于通过原点的同一条直线，无论 y 是正数还是负数。 
3. 如果 x 非零，则计算 x 和 y 的最大公约数，然后将两者除以它。 这会将该对减少到其最小整数表示形式。 此步骤删除重复项，例如 (2, 4) 和 (1, 2)。 
4. 标准化符号，以便等效方向映射相同。 标准规则是确保 x 为正，或者如果 x 为零则 y 为正。 如果 x 为负数，则将两个分量乘以 -1。 
5. 将每个标准化方向存储在哈希图中并增加其频率。 
6. 处理完所有点后，返回所有方向类别中看到的最大频率。 

工作原理：每个点都属于通过原点的一条直线，并且每一条这样的直线都对应于一个简化的方向向量。 归一化保证了几何线和哈希键之间的一对一映射，因此计算频率相当于计算每条有效线上有多少个点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from math import gcd
from collections import defaultdict

def solve():
    n = int(input())
    freq = defaultdict(int)

    for _ in range(n):
        x, y = map(int, input().split())

        if x == 0:
            # vertical line through origin
            key = (0, 1)
        else:
            g = gcd(x, y)
            x //= g
            y //= g

            if x < 0:
                x = -x
                y = -y

            key = (x, y)

        freq[key] += 1

    print(max(freq.values()))

if __name__ == "__main__":
    solve()
```该解决方案独立处理每个点并将其转换为规范方向向量。 gcd 步骤确保所有比例向量折叠成相同的表示。 符号归一化确保同一直线上的相反方向不会分成单独的组。 

一个微妙的实现细节是在尝试 gcd 标准化之前处理 x = 0。 如果没有这个保护，除法逻辑仍然有效，但符号约定变得不一致，特别是对于 (0, y) 和 (0, -y)。 明确修复垂直线可以避免歧义并简化映射。

 ## 边缘情况

 关键的边缘情况是所有点都位于同一几何线上，但以不同的整数比例和符号出现。 例如，(1, 2)、(2, 4) 和(-3, -6)。 该算法通过除以 gcd 并固定符号将它们全部转换为 (1, 2)，因此将它们一起计数。 如果没有这种标准化，这些将被错误地视为不同的方向。 

另一个边缘情况是垂直对齐。 对于 (0, 1)、(0, -1) 和 (0, 5) 等输入，基于斜率的分组将由于除以零或不一致的表示而失败。 到单个规范键 (0, 1) 的显式映射可确保合并所有此类点，并且频率计数正确反映它们位于通过原点的同一条线上。
