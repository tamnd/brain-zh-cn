 ## 解决方案
 ## 问题理解

 我们得到一个长度为整数的数组$n$。 每个位置存储一个数字，代表该袋子中有多少糖果。 对于每个查询，我们采用一个连续的段$[l, r]$并询问我们是否可以重新排序该段内的值，以便在重新排列后该段恰好变成来自的连续整数$l$到$r$。 

换句话说，每个查询都会询问子数组内的值的多重集是否与整数集匹配$\{l, l+1, \ldots, r\}$。 段内的顺序并不重要，重要的是这些值是否可以排列以形成精确的间隔。 

约束条件达到$2 \cdot 10^5$对于两者$n$和$q$，因此任何在时间间隔内以线性时间处理每个查询的解决方案都会立即变得太慢。 扫描每个范围并直接检查条件的简单方法将降级为$O(nq)$，这是周围$4 \cdot 10^{10}$在最坏的情况下运行并且不会及时运行。 

关键的微妙之处在于，这不是对任意值的简单频率检​​查。 目标间隔取决于查询边界本身，这意味着正确性取决于总和结构以及是否存在重复值或缺失值。 

一些边缘案例暴露了常见的错误。 

如果该段是$[1, 3, 2]$为了$l = 1, r = 3$，答案是肯定的，因为它可以置换成$[1, 2, 3]$。 但如果该段是$[1, 3, 2, 5]$为了$l = 1, r = 4$，它是“否”，因为即使值不同，但它们与所需的集合不匹配$\{1,2,3,4\}$。 许多天真的方法所犯的一个错误是只检查值是否在范围内$[l, r]$，这会错误地接受类似的情况$[1,1,2,3]$或者$[1,2,2,3]$。 另一种失败模式是仅检查总和，这是不够的，因为排列如$[1,4]$和$[2,3]$共享相同的总和但代表不同的多重集。 

正确的解决方案必须确保集合的完整性并且不存在额外或重复的值。 

## 方法

 暴力解决方案独立处理每个查询。 对于给定的时间间隔$[l, r]$，我们提取所有值，对它们进行排序，然后与序列进行比较$l, l+1, \ldots, r$。 这是正确的，因为排序暴露了多重集是否与所需的连续结构匹配。 然而，对每个查询进行排序的成本$O((r-l+1)\log(r-l+1))$，退化为$O(n \log n)$每个查询和总体$O(nq \log n)$，远远超出了可行的限度。 

即使删除排序，我们仍然需要一种有效验证两个属性的方法：所有元素都位于$[l, r]$，并且该范围内的每个整数只出现一次。 这表明跟踪计数，但维护每个查询的完整频率数组也太昂贵。 

关键的观察是目标细分市场$[l, r]$具有固定的总和和固定的基数。 如果区间内的多重集完全匹配$[l, r]$，那么两个条件必须同时成立：元素的数量是$r-l+1$，并且元素之和必须等于算术级数之和$\frac{(l+r)(r-l+1)}{2}$。 由于所有值都是整数并且大小是固定的，这两个约束足以保证多重集完全正确，因为值的任何偏差都必然会改变总和。 

这将每个查询减少为数组上的范围和查询，可以用前缀和来回答$O(1)$。

 ## 算法演练

 我们依赖这样一个事实：有效段必须与目标算术级数的长度和精确总和相匹配。 

1. 构建一个前缀和数组，其中`pref[i]`存储第一个的总和$i$数组的元素。 这允许在恒定时间内计算任何范围总和。 这一步将重复的求和工作转化为预计算。 
2. 对于每个查询$[l, r]$，使用计算子数组的总和$\text{sum} = pref[r] - pref[l-1]$。 这给出了该段中当前值的准确总数。 
3. 计算序列的期望和$l, l+1, \ldots, r$使用算术级数公式$\frac{(l+r)(r-l+1)}{2}$。 这代表该段的唯一有效配置。 
4. 比较两个总和。 如果相等则输出YES，否则输出NO。 

我们不显式检查重复项或排序的原因是，对于固定的段长度，将所需总和与整数匹配的唯一方法是匹配精确的集合。 任何缺失或重复的数字都会迫使另一个值发生补偿性变化，从而改变总和。 

## 为什么它有效

 该段必须准确包含$k = r-l+1$整数。 目标多重集正是来自的整数$l$到$r$，这是唯一的集合$k$具有该总和的不同整数。 任何偏差要么引入超出范围的值，要么重复一个值，这两种情况都必然会更改总和，因为用另一个整数替换不同的整数会使总和改变非零量。 这使得总和相等既是必要的又是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        s = pref[r] - pref[l - 1]
        k = r - l + 1
        target = (l + r) * k // 2
        if s == target:
            out.append("YES")
        else:
            out.append("NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现首先在线性时间内构建前缀和。 通过在恒定时间内提取范围总和并将其与预期算术级数总和进行比较来回答每个查询。 除以 2 是安全的，因为$(l+r)k$对于连续整数始终是偶数，因此不会出现精度问题。 

一个微妙的点是索引：前缀和是使用基于 1 的索引构建的，以避免重复的边界检查。 这确保查询计算是直接减法，无需条件处理$l = 1$。

 ## 边缘情况

 关键的边缘情况是当值都在正确的数值范围内但不不同时。 例如，在一个区间内$[1, 3]$，数组段$[1, 1, 3]$has sum 5, while the expected sum is 6. The algorithm correctly rejects it through sum mismatch even though all values appear “plausible”.

 另一种情况是移位间隔，例如$[3, 5]$该段在哪里$[3, 4, 6]$。 6 的存在使总和超出了预期的算术总数，并且相等检查立即失败，无需显式范围验证。 

最后一种情况是按乱序排列的完美排列，例如$[2, 1, 3]$为了$[1, 3]$。 总和在排列下保持不变，因此算法正确地接受它，这表明排序是无关紧要的，只有多重集结构才重要。
