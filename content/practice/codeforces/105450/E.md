 ## 解决方案
 ## 问题理解

 我们得到一排糖果，每个糖果都有一个数值，代表吃该糖果的愉悦程度。 这些值可以是正的，也可以是负的，因此吃糖果可以帮助也可以损害整体的享受。 

在这些糖果中，有一些被标记为水优最喜欢的类型。 铃鹿可以选择数组中任何连续的部分，但有一个限制：所选的部分必须至少包含一种最喜欢的糖果。 在所有这些有效段中，我们想要最大可能的值之和。 

因此，任务是一个受约束的最大子数组问题：我们不考虑任何子数组，而是只考虑那些至少包含一个索引且标记数组等于 1 的子数组，并且我们想要其中的最大总和。 

约束最多允许 200,000 个糖果，因此任何直接尝试所有子数组的解决方案都太慢。 重复重新计算总和的二次或三次方法将涉及大约$O(n^2)$或者更糟糕的操作，远远超出了1秒的限制。 我们需要一些线性或近线性的东西。 

有两个微妙的失败案例常常打破天真的推理。 

当除了一种最喜欢的糖果之外所有糖果都是负面的时，就会出现一个问题。 一个简单的 Kadane 算法会正确地选择总体上最好的子数组，但是简单地“跟踪包含最喜欢的子数组”而不进行仔细的边界处理的修改可能会错误地扩展到更糟糕的负区域或排除最佳的单个最喜欢的子数组。 

当最佳子数组包含多个最喜欢的糖果，并且最佳选择不是以最喜欢的糖果为中心而是跨越它时，就会出现另一个问题。 如果天真地尝试固定一个最喜欢的位置并在左右两侧独立运行 Kadane，而没有正确分配贡献，则可能会错过最佳传中。 

## 方法

 暴力破解的想法很简单：枚举每个可能的子数组，检查它是否包含至少一种最喜欢的糖果，计算其总和并跟踪最大值。 这是正确的，因为它直接评估问题的定义。 

然而，大约有$n(n+1)/2$子数组。 为了$n = 200000$，这是关于$2 \times 10^{10}$子数组，即使可以在恒定时间内检查每个子数组，我们仍然会超出数量级的限制。 天真地计算总和会使情况变得更糟。 

关键的见解是重新构建约束。 我们可以将解决方案锚定在每个最喜欢的位置周围，而不是将“必须包含至少一个最喜欢的”视为对子数组的全局限制。 任何有效的子数组都必须包含一些最喜欢的索引，因此最佳答案是子数组内最喜欢的位置的所有选择中的最大值。 

修复最喜欢的索引$i$。 我们想要包含的最佳子数组$i$。 该子数组可以分为三个部分： 左扩展结束于$i$，值在$i$，以及从以下位置开始的右扩展$i$。 最优选择是独立最大化以结尾的最佳后缀$i$以及从以下位置开始的最佳前缀$i$，但两者都必须非空，因为如果继续减少总和，则允许它们提前停止。 

这将问题简化为针对每个索引计算以该索引结束的最佳子数组（经典的 Kadane 前向传递）以及从该索引开始的最佳子数组（向后 Kadane 传递）。 然后对于每个最喜欢的索引$i$，我们将左右贡献结合起来。 

这是有效的，因为最佳子结构成立：包含的最佳段$i$分解为结束于的最佳片段$i$从左边开始，最佳段开始于$i$从右侧进行，两侧互不干扰。

 | --- | --- | --- | --- |
 | 蛮力 |$O(n^3)$或者$O(n^2)$|$O(1)$| 太慢了|
 | 最佳 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们构造两个数组。 一个存储在每个位置结束的最大子数组和，另一个存储从每个位置开始的最大子数组和。 

1. 计算一个前向动态规划数组，其中对于每个索引$i$，我们决定是否扩展前一个子数组或从新开始$i$。 这给出了结束于的最佳总和$i$。 该决定反映了先前累积的金额是有益​​的还是有害的。 
2. 使用相同的逻辑以相反的顺序计算从每个索引开始的子数组的向后版本。 这捕获了最佳的右扩展。 
3. 对于每个位置$i$被标记为最喜欢的，计算使用的最佳有效子数组$i$作为“桥点”。 这是通过结合结束于的最佳贡献来完成的$i$从左边开始$i$从右边开始，减去$a[i]$一次以避免重复计算。 
4. 跟踪所有喜爱位置的最大值。 

需要减法的原因是左DP和右DP都包含索引处的值$i$。 如果不纠正这种重叠，该元素将被计数两次。 

### 为什么它有效

 任何有效的子数组必须至少包含一个最喜欢的索引。 修复一个最喜欢的索引$i$。 任何包含的子数组$i$可以唯一地分割成以以下结尾的左侧部分$i$和一个开始于的右侧部分$i$。 最好的这种分解在两侧都是独立的，因为一侧的任何限制不会影响另一侧的有效选择。 DP 数组保证对于每一侧，我们已经存储了任何边界的最佳选择。 因此，在每个最喜欢的索引处将它们组合起来可以无遗漏地探索所有有效的子数组，并取最大值确保最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    left = [0] * n
    right = [0] * n

    left[0] = a[0]
    for i in range(1, n):
        left[i] = max(a[i], left[i - 1] + a[i])

    right[n - 1] = a[n - 1]
    for i in range(n - 2, -1, -1):
        right[i] = max(a[i], right[i + 1] + a[i])

    ans = -10**18

    for i in range(n):
        if b[i] == 1:
            val = left[i] + right[i] - a[i]
            ans = max(ans, val)

    print(ans)

if __name__ == "__main__":
    solve()
```前向传递构建`left[i]`作为必须完全在索引处结束的最佳子数组`i`。 这是标准的 Kadane 循环，我们要么延长前一段，要么重新开始。 

向后传递反映了从每个索引开始的后缀的这一想法。 

当评估最喜欢的指数时，我们将两个 DP 值结合起来并减去`a[i]`因为两边都包含了。 这确保了子数组只被计算一次。 

最终的答案是所有最喜欢的位置中的最大值。

 ## 边缘情况

 当数组包含由大负值包围的单个最喜欢的元素时，前向和后向 DP 数组仍然正确计算以该索引结束和开始的最佳段作为元素本身。 组合公式简化为该值，因为两侧仅贡献长度为 1 的最佳子数组。 

当所有元素都是收藏夹时，每个索引都是有效的锚点，并且算法简化为检查所有可能的以收藏夹为中心的组合。 所有锚点的最大值与全局最大子数组匹配，因为每个子数组根据定义至少包含一个最喜欢的。
