 ## 解决方案
 ## 问题理解

 我们拥有一组机器，每台机器都可以配置为三个生产角色之一，也可以不使用。 如果设置一台机器来生产糖果形状，就会贡献一定的能源成本； 如果设置为添加酸味，则会贡献另一项成本； 如果将其设置为环绕，则会产生第三个成本。 不使用它不会有任何贡献。 

工厂要求严格：准确$x$机器必须准确地分配给成型$y$酸味，确切地说$z$来包装。 每台机器最多只能使用一次，其余机器可以闲置。 目标是将角色分配给机器，以便满足所有配额，同时最大限度地减少总能耗。 

就机器数量而言，输入规模很大，最多可达$10^5$，但所需的计数$x, y, z$很小，每个最多 100 个。这种不平衡是中心结构线索：复杂性压力来自机器数量，而不是所需作业的数量。 

一种简单的方法是尝试独立分配每台机器或探索所有机器上的分配组合。 这很快就会失败，因为每台机器都有四个选择，并且由于配额限制，选择之间存在依赖关系。 如果直接以密集方式实现，即使是对所有机器和所有配额状态进行简单的动态编程也会变得太慢。 

一个常见的陷阱是贪婪地对待每台机器，例如将其分配给三个角色中最便宜的角色。 但这会失败，因为早期的廉价选择可能会阻碍以后的任务。 例如，如果两台机器的整形都很便宜，但只有一个插槽存在，那么贪婪地采用两台机器进行整形可能会迫使稍后进行昂贵的分配，而稍微昂贵的早期决策将允许更好的全局配置。 

另一个微妙的问题是正确忽略“未使用”选项。 强制每台计算机担任三个角色之一的解决方案将超出配额并产生不正确或不可能的配置。 

## 方法

 直接的强力视图是决定每台机器是否成型、酸化、包装或保持未使用状态。 这创造了$4^n$的可能性，即使对于中等程度的人来说也是完全不可行的$n$， 作为$n = 100$已经产生了天文数字般巨大的搜索空间。 

自然的细化是动态规划到目前为止已分配给每个角色的机器数量。 让状态跟踪在处理机器的某​​些前缀后已进行了多少形状、酸和包装分配。 每台机器都会转变为四种可能性，因此状态图变成分层的 3D 网格。 这个想法是正确的，但是直接实现更新$O(xyz)$每个状态$n$机，导致大约$10^5 \cdot 10^6 = 10^{11}$操作，规模太大了。 

关键的观察是，这不是一个顺序决策问题，其中每台机器必须以 DP 逐层方式独立处理。 相反，这是一个约束分配问题：我们正在准确地选择$x+y+z$机器总数，每台选定的机器都被分配到三个类别之一，其成本取决于分配。 

这种结构非常自然地匹配最小成本流公式。 每台机器都是一个项目，最多可以将一个单位的流量发送到三个类别桶中的一个。 每个类别都有固定的需求。 未使用的选项对应于不通过该机器发送流。 一旦以这种方式构建，问题就变成了一个标准流程，总所需流程很小（$\le 300$），它足够小，即使使用相对简单的最小成本最大流实现也可以处理。 

流程图自动强制执行全局一致性，无需复杂的 DP 状态管理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(4^n)$|$O(n)$| 太慢了|
 | DP 超计数 |$O(nxyz)$|$O(xyz)$| 太慢了|
 | 最小成本流程|$O(F \cdot E \log V)$和$F \le 300$|$O(E)$| 已接受 |

 ## 算法演练

 我们将问题重新表述为一个流网络，其中每个有效分配都对应于一个流$x+y+z$单位，每个单位代表将一台机器分配给一个角色。 

1. 构建一个源节点，并将其连接到容量为1、成本为零的每个机器节点。 这强制每台机器最多只能使用一次。 
2. 从每个机器节点创建到三个角色节点的边：形状、酸度和包装。 每条边的容量为 1，成本等于相应的能源成本$a_i$,$b_i$， 或者$c_i$。 这编码了将该机器分配给角色的成本。 
3. 不要将机器节点直接连接到“接收器”。 相反，通过角色节点路由所有分配，因为角色节点强制执行全局配额。 
4. 从每个角色节点，连接到容量等于该角色所需机器数量的接收器，即$x$,$y$， 和$z$，每个成本为零。 这强制要求为每个角色分配的计算机数量不得超过所需数量。 
5. 运行从源到汇的最低成本流程，精确推动$x+y+z$流量单位。 每个单元对应选择一台机器并分配给它一个角色。 
6. 由此产生的最小成本就是答案。 

正确性背后的关键思想是，每个有效的分配都对应一个唯一的可行流程：选择一台机器并将其分配给一个角色正是选择一条路径源→机器→角色→汇。 相反，任何可行的流都遵守容量限制，因此它永远不会分配超过可用的机器或超过角色配额。 

## 为什么它有效

 流网络将所有约束编码为容量限制而不是显式组合条件。 机器唯一性是通过源到机器容量 1 来强制执行的。角色配额是通过限制进入每个角色节点的总传入流量来强制执行的。 成本沿边缘完全累加，因此最小化流动成本直接最小化总能量。 

由于每个流单元恰好对应一个机器分配，因此大小的可行流之间存在一一对应关系$x+y+z$和有效的工厂。 这消除了对子集或计数进行显式状态跟踪的需要。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import deque

INF = 10**18

class Edge:
    __slots__ = ("to", "cap", "cost", "rev")

    def __init__(self, to, cap, cost, rev):
        self.to = to
        self.cap = cap
        self.cost = cost
        self.rev = rev

class MinCostFlow:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, fr, to, cap, cost):
        fwd = Edge(to, cap, cost, len(self.g[to]))
        rev = Edge(fr, 0, -cost, len(self.g[fr]))
        self.g[fr].append(fwd)
        self.g[to].append(rev)

    def min_cost_flow(self, s, t, maxf):
        n = self.n
        res = 0
        h = [0] * n

        prevv = [0] * n
        preve = [0] * n

        while maxf > 0:
            dist = [INF] * n
            dist[s] = 0
            inq = [False] * n
            q = deque([s])
            inq[s] = True

            while q:
                v = q.popleft()
                inq[v] = False
                for i, e in enumerate(self.g[v]):
                    if e.cap > 0 and dist[e.to] > dist[v] + e.cost + h[v] - h[e.to]:
                        dist[e.to] = dist[v] + e.cost + h[v] - h[e.to]
                        prevv[e.to] = v
                        preve[e.to] = i
                        if not inq[e.to]:
                            inq[e.to] = True
                            q.append(e.to)

            if dist[t] == INF:
                break

            for v in range(n):
                if dist[v] < INF:
                    h[v] += dist[v]

            d = maxf
            v = t
            while v != s:
                d = min(d, self.g[prevv[v]][preve[v]].cap)
                v = prevv[v]

            maxf -= d
            res += d * h[t]

            v = t
            while v != s:
                e = self.g[prevv[v]][preve[v]]
                e.cap -= d
                self.g[v][e.rev].cap += d
                v = prevv[v]

        return res

def solve():
    n, x, y, z = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    c = list(map(int, input().split()))

    S = 0
    T = 1 + n + 3
    A = 1 + n
    B = 1 + n + 1
    C = 1 + n + 2

    mcf = MinCostFlow(T + 1)

    for i in range(n):
        mcf.add_edge(S, 1 + i, 1, 0)
        mcf.add_edge(1 + i, A, 1, a[i])
        mcf.add_edge(1 + i, B, 1, b[i])
        mcf.add_edge(1 + i, C, 1, c[i])

    mcf.add_edge(A, T, x, 0)
    mcf.add_edge(B, T, y, 0)
    mcf.add_edge(C, T, z, 0)

    print(mcf.min_cost_flow(S, T, x + y + z))

if __name__ == "__main__":
    solve()
```该实现构建了一个类似二分的流结构，其中机器位于源节点和角色节点之间。 最小成本流程例程使用最短路径重新加权方法，具有安全处理负降低成本的潜力。 每次增强都会沿着最便宜的可用分配路径推送尽可能多的流量，并且由于总流量很小，因此重复的最短路径计算仍然有效。 

一个微妙的细节是，一旦发送了所需的流量，算法就会停止。 如果网络构建不正确，流量将提前停止或超出容量，从而使此类错误表现为不完整或不可能的流量。

 ## 边缘情况

 一种关键的边缘情况是，一个角色对于许多机器来说极其便宜，但其配额很小。 贪婪的分配会导致该角色过早超载，从而迫使稍后进行昂贵的重新分配。 在流公式中，这是自然处理的，因为角色节点的容量防止超过$x$，因此多余的流量被迫进入替代角色。 

另一种情况发生在一台机器有一个极其占优势的选项和两个较差的选项时。 朴素的启发式方法可能总是选择最佳的本地成本，但如果该选项已经被早期的流程饱和，则该算法会正确地通过其第二最佳边缘重新路由该机器，而不会破坏可行性。 

最后，当所有机器具有相同的成本时，算法会探索多个等效的增强路径，但任何有效的最小成本流都将在仍然尊重配额的同时任意分配分配，从而产生相同的总成本。
