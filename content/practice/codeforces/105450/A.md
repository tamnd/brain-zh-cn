 ## 解决方案
 ## 问题理解

 我们得到了代表糖果的整数酸度值列表。 允许爱丽丝完全删除$k$从此列表中取出糖果，留下$n-k$后面有糖果。 删除后，我们查看剩余的集合，并通过最大和最小剩余值之间的差值来衡量它的“分散”程度。 目标是选择要移除的糖果，以使最终的糖果分布尽可能小。 

换句话说，我们并不是试图直接控制某个选定子集中的成对差异，而是控制删除后剩余内容的范围。 目标简化为使剩余值尽可能紧密地聚集在数轴上。 

限制条件$n \le 1000$允许一个粗略的解决方案$O(n^2)$，而且还可以使用排序和滑动窗口，而无需考虑性能。 任何事物$O(n^3)$或者更糟糕的是，大规模的风险会很大，但即使$O(n^2)$会很舒服地过去。 

当所有数字都相同时，就会出现微妙但重要的边缘情况。 在这种情况下，每个子集的范围都为零，并且无论删除如何，答案都必须为零。 另一种边缘情况是移除后只剩下一颗糖果，这意味着$n-k=1$。 单个元素的范围始终为零，任何正确的方法都必须显式或隐式地处理这个问题。 

一种常见的错误方法是贪婪地删除两端的极值而不考虑最佳连续块。 当最优解不居中或存在多个密集簇时，这可能会失败。 例如，具有如下值$[1, 2, 3, 100, 101]$，即使存在紧密的障碍，消除错误的极端也可能会留下很大的差距。 

## 方法

 蛮力的想法很简单：尝试每个可能的大小子集$n-k$，计算其最小值和最大值，并跟踪最小的可能范围。 这是正确的，因为它检查所有配置，但在计算上是不可行的。 子集的数量是$\binom{n}{n-k}$，呈指数级增长，甚至对于$n=30$。 

关键的观察是，只有值的相对顺序很重要，而不是它们的原始位置。 一旦数组排序完毕，任何最佳剩余大小集$n-k$必须包含按此排序顺序的连续元素。 如果它不连续，则选择范围内会存在间隙，并且用更接近的缺失元素替换极端元素总是会减小或维持范围。 

这减少了选择窗口大小的问题$n-k$在排序数组中并最小化其端点之间的差异。 每个窗口代表保留一组紧密包装的糖果并丢弃外面的所有东西。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(\binom{n}{k} \cdot n)$|$O(n)$| 太慢了|
 | 排序+滑动窗口|$O(n \log n)$|$O(1)$额外 | 已接受 |

 ## 算法演练

 1. 对数组进行非降序排序。 排序会组织所有候选，以便任何最佳子集都成为此排序中的连续段。 
2. 计算剩余的糖果数量，$m = n - k$。 这是我们必须评估的窗口的固定大小。 
3.滑动大小窗口$m$穿过已排序的数组。 对于从索引开始的每个窗口$i$，窗口覆盖来自的元素$i$到$i+m-1$。 
4. 对于每个窗口，计算其最后一个元素与第一个元素之间的差异。 这个值代表了我们保留这些糖果的范围。 
5. 跟踪所有窗口中的最小此类差异并将其输出。 

每个步骤都是必要的，因为排序创建结构，窗口强制子集大小约束，并且评估端点直接捕获范围而无需在窗口内扫描。 

### 为什么它有效

 排序后，大小的任何子集$m$可以通过用子集外部更接近的元素替换大的内部间隙来改善不连续的情况。 这种替换不会增加范围，而且经常会减少范围。 重复这个论证会迫使最优解成为一个连续的块。 因此，每个最优解恰好对应一个长度的滑动窗口$m$，并检查所有此类窗口以保证正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort()
    
    m = n - k
    if m <= 1:
        print(0)
        return
    
    ans = float('inf')
    
    for i in range(n - m + 1):
        ans = min(ans, a[i + m - 1] - a[i])
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先对数组进行排序，以便任何最佳选择都必须显示为连续的块。 变量`m`代表移除后剩余的糖果数量。 如果只剩下一颗糖果，则答案立即为零，因为不存在传播。 

循环检查每个可能的窗口大小`m`。 对于每个起始索引`i`， 区别`a[i + m - 1] - a[i]`计算该段的范围。 所有窗口的最小值是可实现的最佳配置。 

一个常见的实施错误是使用`n-k`错误地表示为已删除元素的数量而不是剩余元素的数量。 另一个微妙的问题是忘记最后一个有效窗口开始于`n-m`， 不是`n-m+1`。

 ## 边缘情况

 对于单元素剩余情况，如输入：```
3 2
10 1 7
```排序后，我们得到 [1, 7, 10] 和$m = 1$。 该算法立即返回 0，因为任何单个元素窗口的范围都为零。 这可以避免访问无效的窗口端点并正确反映范围的定义。 

对于所有相等的值：```
5 2
7 7 7 7 7
```任何大小的每个窗口都有相同的端点，因此每个计算范围都是 0。最小值仍然是 0，并且算法自然地处理这个问题而无需特殊的大小写。 

对于相距较远的集群：```
6 2
1 2 3 100 101 102
```排序数组已经显示了两个紧密的组。 大小为 4 的 Windows 将包含两个簇或仅包含一个簇。 最佳窗口是 [1, 2, 3, 100]（给出范围 99），或 [2, 3, 100, 101]（给出 99）。 这证实了该算法系统地评估了所有候选的连续选择，并且不会错过分裂集群配置。
