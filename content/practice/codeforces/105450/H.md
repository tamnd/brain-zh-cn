 ## 解决方案
 ## 问题理解

 我们有一个矩形网格，其中每个单元格要么可用，要么被阻止。 标记从左上角的单元格开始，两名玩家交替移动。 在一回合中，玩家将令牌向下、向右或对角线右下移动一步，但前提是目标单元格位于网格内且未被阻挡。 如果玩家没有合法的动作，则该玩家立即失败。 

任务是确定第一个玩家 Alice 是否有获胜策略。 

网格大小可以大到 1000 x 1000，这使得任何试图探索所有移动序列的解决方案都明显不可行。 每个单元的完整博弈树将向三个方向分支，并且深度可以与 r + c 成比例呈指数增长，因此简单的递归搜索将超出时间限制许多数量级。 

一个微妙的问题是，被阻挡的单元格可能会产生孤立的区域，使某些位置成为死胡同，即使它们不在边界附近。 例如，除向后方向外被黑色方块包围的单元格是无关的，因为不允许向后移动，因此它实际上变成了最终失败状态。 

另一种边缘情况是起始单元根本没有有效的移动。 即使它保证是白色的，但它仍然可能完全被黑色或边界包围，导致爱丽丝立即损失。 

## 方法

 游戏的直接模拟将每个白细胞视为游戏状态，并递归地探索所有可到达的动作。 从每个状态，我们检查是否存在移动到对手失败的位置。 这是有向图上公正博弈的标准极小极大定义。 

然而，这个递归多次重复相同的子问题。 在最坏的情况下，每个 r × c 单元都可以分支为三个转换，从而导致指数行为。 即使使用记忆，结构也是非循环的，因为所有移动都会增加行或列，因此每个状态仅取决于网格中“稍后”的单元格。 

这种单调结构是关键的观察结果。 由于每次移动都会严格增加任一坐标，因此不存在循环。 这意味着我们可以自下而上地计算结果：任何单元格仅依赖于其右侧、下方或右下对角线的单元格。 如果我们以相反的顺序处理网格，从右下角到左上角，每个转换都会导致一个已经计算过的状态。 

对于每个白色单元格，如果它可以移动到至少一个失败的单元格，我们将其标记为获胜。 如果所有可能的移动都导致获胜位置，则当前单元格正在失败。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力DFS | O(3^(r+c)) | O(3^(r+c)) | O(r·c) 递归 | 太慢了|
 | 自下而上的DP | O(r·c) | O(r·c) | 已接受 |

 ## 算法演练

 我们将每个单元格建模为要么获胜要么失败的游戏状态。 

1. 我们创建一个 DP 表，其中每个单元格存储从该位置开始的当前玩家是否可以强制获胜。 黑色单元格总是失败，因为站在它上面是无效的。 
2. 我们以相反的顺序迭代网格，从右下角开始向左上角移动。 这个顺序保证了每当我们评估一个单元格时，它可以移动到的所有单元格都已经被处理过。 
3. 对于每个白色单元格，我们尝试所有有效的移动：向下、向右和对角线右下。 如果这些动作中的任何一个导致单元格失败，我们将当前单元格标记为获胜。 理由是我们可以迫使对手陷入失败的境地。 
4. 如果没有一个动作导致失败状态，我们将当前单元格标记为失败，因为每一步动作都会给对手带来获胜位置。 
5. 填写完 DP 表后，答案由起始单元格 (0,0) 处的值确定。 如果赢了，Alice就可以强行获胜，否则Bob就赢了。 

### 为什么它有效

DP 表对 DAG 上公正博弈的基本属性进行了编码：当一个位置至少有一个相对于失败位置的传出边缘时，该位置就获胜。 由于移动图是非循环的，因此每个状态仅严格依赖于处理顺序中较晚的状态，因此每个值仅计算一次并且永远不会失效。 这确保了局部决策和全局游戏结果之间的一致性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    r, c = map(int, input().split())
    grid = [input().strip() for _ in range(r)]
    
    dp = [[False] * c for _ in range(r)]
    
    for i in range(r - 1, -1, -1):
        for j in range(c - 1, -1, -1):
            if grid[i][j] == 'B':
                dp[i][j] = False
                continue
            
            win = False
            
            if i + 1 < r and grid[i + 1][j] == 'B':
                win = win or not dp[i + 1][j]
            elif i + 1 < r:
                win = win or (not dp[i + 1][j])
            
            if j + 1 < c:
                win = win or (not dp[i][j + 1])
            
            if i + 1 < r and j + 1 < c:
                win = win or (not dp[i + 1][j + 1])
            
            dp[i][j] = win
    
    print("Alice" if dp[0][0] else "Bob")

if __name__ == "__main__":
    solve()
```实现的核心是网格的反向遍历。 每个 dp 单元仅计算一次，并且转换仅在网格中向前进行。 布尔逻辑直接捕捉极小极大规则：如果任何举动导致失败状态，则该位置将成为获胜位置。 

唯一的微妙之处是处理黑色单元格。 它们是被迫失败的状态，绝不能被视为有效的移动目标。 这是通过立即为它们分配 False 并跳过转换来强制执行的。

 ## 边缘情况

 由单个白色单元格组成的最小网格立即结束游戏。 DP 将其标记为失败，因为没有任何传出动作，因此 Bob 被宣布为获胜者。 

如果网格中起始单元的每个邻居都被阻塞，也会导致爱丽丝立即损失。 DP 没有找到从 (0,0) 开始的任何转换，因此它仍然为 False，正确地模拟了最终状态。 

完全开放的网格表现不同：每个单元格最终至少有一次移动到右下边界附近的失败位置，向后传播获胜状态，直到开始变为获胜。
