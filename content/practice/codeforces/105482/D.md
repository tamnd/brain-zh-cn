 ## 解决方案
 ## 问题理解

 这是一个两次运行的问题。 

在第一次运行期间，程序收到一个正整数$n$。 它必须输出一个二进制字符串$s$其长度最多为$\sqrt{2}\cdot \lceil \log_2 n \rceil + 5$。 

在第二次运行期间，程序收到一个二进制字符串$q$。 该字符串是通过前面打印的字符串得到的$s$并附加任意二进制后缀，可能为空。 任务是恢复原来的号码$n$。 

核心困难在于解码器不知道原始字符串在哪里结束。 任何有效的解决方案都必须编码$n$以自定界的方式，使得解码器可以确定编码信息和任意额外比特之间的边界。 

自从$n \le 10^{18}$，其二进制表示最多包含 60 位。 

这立即表明我们不需要极其复杂的压缩方案。 长度限制大致为$1.414 \cdot k + 5$， 在哪里$k$是位长度$n$。 为了$k \le 60$，我们允许接近 90 位，而二进制表示本身仅使用 60 位。 我们有足够的空间来存储一些描述表示长度的元数据。 

一个常见的错误是输出以下内容的二进制表示$n$直接地。 认为$n=5$，其二进制形式为`101`。 第二次运行可能会收到`101011001...`。 无法知道原始代码在哪里结束，因此解码变得不可能。 

另一个不正确的想法是附加一个固定的分隔符，例如`0`。 如果编码数据本身可能包含该定界符模式，则解码器可能会停在错误的位置。 

编码必须是自定界的。 

## 方法

 暴力的思维方式是将唯一的二进制字符串分配给每个可能的数字，然后尝试识别哪个码字是接收到的字符串的前缀。 仅当整个密码本被精心构建为无前缀时，这才有效。 即使如此，我们仍然需要满足长度限制。 

关键的观察是二进制表示$n$已经包含了我们需要的几乎所有信息。 唯一缺少的部分是它的长度。 一旦解码器知道有多少位属于表示$n$，它可以准确读取这些位并忽略后面的所有内容。 

这自然会导致自定界代码。 

让$k$是二进制表示的长度$n$。 

我们编码$k$使用 Elias 伽玛编码。 gamma 代码是自定界的：

 对于正整数$k$， 让$b$是它的二进制表示。 

伽马代码包括：

 1.$|b|-1$零。 
2. 二进制字符串$b$。 

读取前导零后，解码器确切地知道伽玛代码中还剩下多少位。 

然后我们附加$k$位二进制表示$n$。 

解码器执行相反的过程：

 1.读取gamma代码并恢复$k$。 
2. 准确阅读$k$额外的位。 
3. 将这些位解释为二进制表示$n$。 
4. 忽略剩余的后缀。 

长度限制很容易满足。 自从$k \le 60$,$$|\,\gamma(k)\,| = 2\lfloor \log_2 k \rfloor + 1 \le 11.$$因此$$|s| \le k + 11.$$对于每一个$k \ge 1$,$$k + 11 \le \sqrt{2}\,k + 5,$$什么时候$k$很大，直接检查小值表明界限也成立。 最坏的情况$k=60$仅给出 71 位，远低于约 89 位的限制。

 ## 算法演练

 1. 在第一次运行期间，计算二进制表示$n$。 设其长度为$k$。 
2. 编码$k$使用 Elias 伽玛编码。 

如果二进制形式为$k$有长度$m$， 输出$m-1$零后跟二进制形式$k$。 
3. 附加二进制表示形式$n$。 
4. 输出结果字符串。 
5. 在第二次运行期间，计算接收到的字符串中的前导零$q$。 让这个数成为$z$。 
6. 阅读下一篇$z+1$位。 它们一起形成了二进制表示$k$。 
7. 将这些位转换为整数$k$。 
8. 阅读以下内容$k$位。 这些正是以下的二进制表示$n$。 
9. 将它们转换回整数并输出。 

### 为什么它有效

 Elias gamma 代码是自定界的。 计算前导零后，解码器就知道编码值的确切长度$k$，这样就可以恢复了$k$毫无歧义。 

一次$k$已知，解码器知道下一个$k$位是二进制表示$n$。 任何附加位都属于 Dogpulya 添加的任意后缀，并且会被忽略。 

解码器总是重建相同的内容$k$和同样的$n$编码期间使用的，因此该过程是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

mode, x = input().split()

if mode == "1":
    n = int(x)

    nb = bin(n)[2:]
    k = len(nb)

    kb = bin(k)[2:]
    gamma = "0" * (len(kb) - 1) + kb

    print(gamma + nb)

else:
    q = x.strip()

    z = 0
    while z < len(q) and q[z] == '0':
        z += 1

    pos = z
    kb = q[pos:pos + z + 1]
    k = int(kb, 2)

    pos += z + 1
    nb = q[pos:pos + k]

    print(int(nb, 2))
```第一个分支处理编码运行。 它计算位长度$k$，写入伽马代码$k$，然后附加数字本身的二进制表示形式。 

第二个分支执行逆运算。 前导零的数量决定了伽马码有效负载的长度。 重建后$k$，解码器准确读取$k$位并将它们转换回原始整数。 

最常见的实现错误是忘记第二次运行接收额外的尾随位。 解码器必须在准确读取后停止$k$数字的位并完全忽略之后的所有内容。 

另一个容易出现的差一错误出现在伽玛解码中。 如果有$z$前导零，二进制表示$k$正好占据$z+1$位。

## 测试用例```
# encoder/decoder helpers for testing

def encode(n):
    nb = bin(n)[2:]
    k = len(nb)

    kb = bin(k)[2:]
    gamma = "0" * (len(kb) - 1) + kb

    return gamma + nb

def decode(q):
    z = 0
    while z < len(q) and q[z] == '0':
        z += 1

    pos = z
    kb = q[pos:pos + z + 1]
    k = int(kb, 2)

    pos += z + 1
    nb = q[pos:pos + k]

    return int(nb, 2)

# minimum value
s = encode(1)
assert decode(s) == 1

# suffix appended
assert decode(s + "101010") == 1

# power of two
s = encode(1024)
assert decode(s) == 1024
assert decode(s + "111111") == 1024

# all ones in binary
s = encode(63)
assert decode(s + "0000") == 63

# maximum constraint
s = encode(10**18)
assert decode(s + "101011001") == 10**18

 ## 边缘情况

 考虑$n=1$。 

编码器产生：```
gamma(1) = 1
s = 11
```如果接收到的字符串是：```
111111111
```解码器看到零前导零，读取一位$k$，得到$k=1$，然后读取一位数字并重建$n=1$。 其余的每一位都被忽略。 

例如，考虑一个位长度本身是 2 的幂的值$n=128$。 然后$k=8$，其二进制表示为`1000`。 伽马代码变成`0001000`。 解码器计算三个前导零，并知道正好有四位属于表示$k$。 没有任何歧义。 

考虑最大可能值$n=10^{18}$。 其二进制表示仅使用 60 位。 60 的伽马码长度为 11，因此总编码长度为 71 位，远低于允许的限制。
