 ## 问题理解

 我们得到一个带有加权边的无向连通图。 该图有一个特殊的结构限制：任何包含顶点 1 的简单环的长度最多只能为 3，这意味着顶点 1 不是任何比三角形长的简单环的一部分。 这严重限制了顶点 1 周围的边与图的其余部分相互作用的方式。 

路径的成本定义为沿其所有边权重的异或，其中如果多次遍历，边会贡献多次。 我们关心的是总异或为零的循环。 如果此类循环在至少一条边被使用奇数次的意义上非常重要，则称为不良循环。 

我们可以删除与顶点 1 相关的边的任何子集。删除后，我们要确保不存在通过 XOR 成本为零的非平凡循环。 我们必须计算有多少个与顶点 1 相关的边子集满足此条件。 

关键的观察结果是只有与顶点 1 相邻的边是可控的。 图中的其他所有内容都是固定的，因此涉及顶点 1 的所有可能循环的结构取决于其邻居如何通过图的其余部分相互连接。 

约束最多为 100000 个顶点和边。 这立即排除了枚举一般边的循环或子集。 任何解决方案都必须将问题简化为接近线性或线性算术的问题，可能依赖于异或值的结构分解或线性代数。 

一种简单的方法会尝试与顶点 1 相关的所有边子集。如果度数为 d，则为 O(2^d)。 在最坏的情况下 d 可能是 O(n)，所以这是不可能的。 

一个更微妙的失败案例来自于假设可以对每个边缘独立检查周期。 例如，如果存在两条边 1-u 和 1-v，并且 u 和 v 之间存在 XOR 为零的路径，则保留两条边会产生不良循环，即使每条边单独看起来都是安全的。 这种相互依赖是主要的困难。 

## 方法

 强力解决方案选择与顶点 1 相关的边的子集，然后检查是否存在包含顶点 1 的任何坏循环。即使我们有一个快速循环检查预言机，枚举子集的次数也是顶点 1 的指数级，这太大了。 

要理解结构，请考虑涉及顶点 1 的循环是什么样的。 任何这样的循环必须从 1 开始，到达某个邻居 u，穿过图，返回到 1 的另一个邻居 v，然后通过边 (v, 1) 关闭循环。 因此，通过 1 的每个循环都对应于图中删除了顶点 1 的 1 的两个邻居之间的路径。 

循环 1-u ... v-1 的 XOR 条件为：

 XOR(边 1-u) XOR（沿路径 u 到 v 的异或） XOR XOR(边 v-1) = 0。 

重写一下，就变成：

 XOR(边 1-u) XOR XOR(边 v-1) = XOR(路径 u 到 v)。 

这是对顶点 1 处的成对入射边的约束。邻居之间的每条路径定义了边选择之间的线性 XOR 关系。 

因此，顶点 1 的每个邻居都可以分配一个标签，即删除顶点 1 后到图中某个固定根的 XOR 距离。然后 u 和 v 之间的每个路径 XOR 就是 dist[u] XOR dist[v]。 条件变为：

 如果 dist[u] XOR dist[v] 等于weight(1-u) XOR Weight(1-v)，则禁止选择边 u 和 v。 

所以每条边 (1-u) 都贡献一个值：

 a[u] = dist[u] 异或 w(1-u)。 

那么坏的情况就变成了：

 a[u] = a[v]。 

因此，任何两个端点产生相等值的保留边都会创建禁止配置。 这意味着在所有选定的边中，所有 a[u] 值必须不同。

现在问题变成了：我们有一组与 1 相关的边的值 a[u]，并且我们想要计算没有重复值的子集。 如果一个值出现 k 次，我们最多可以选择其中一个或不选择一个，因此贡献是每个不同值的 (k + 1) 个选择。 

因此，答案是 (频率 + 1) 的所有不同 a 值的乘积。 

图限制保证了 XOR 距离的一致性，并确保通过顶点 1 的循环不会超出成对约束而产生更复杂的依赖关系。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对子集的暴力破解 | O(2^d + 循环检查) | O(n + m) | 太慢了|
 | 异或标签减少 | O(n + m) | O(n) | 已接受 |

 ## 算法演练

 1. 从概念上删除顶点 1，并使用 DFS 或 BFS 计算从顶点 1 到所有其他顶点的 XOR 距离。 我们处理 dist[1] = 0 并遍历边，保持 dist[v] = dist[u] XOR w(u, v)。 这是可行的，因为图在 XOR 约束下是一致的。 
2. 对于直接连接到顶点 1 的每条边，计算值 a[u] = dist[u] XOR w(1, u)。 该值捕获了选择该边相对于图形中所有其他可能路径的有效“签名”。 
3. 计算顶点 1 的所有邻居中每个 a[u] 的频率。每个不同的值表示彼此冲突的边的等价类。 
4. 对于出现 k 次的每个不同值，我们有 k 个选择从中选取一条边，再加上一个选择不选取任何一条边。 将所有这些贡献乘以模 1e9+7。 
5. 返回最终结果作为答案。 

### 为什么它有效

 修复通过顶点 1 的任何循环。它对应于选择两个关联边 (1-u) 和 (1-v) 以及 u 和 v 之间的路径。XOR 条件精确地简化为它们的变换值 a[u] 和 a[v] 相等。 因此，任何无效配置都精确地对应于从同一等价类中选择两条边。 相反，如果没有类贡献多于一个选定的边，则无法形成通过顶点 1 的零 XOR 循环。 这将全局循环约束减少为独立的每类计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    edges = []

    for _ in range(m):
        a, b, w = map(int, input().split())
        g[a].append((b, w))
        g[b].append((a, w))
        edges.append((a, b, w))

    dist = [-1] * (n + 1)
    dist[1] = 0
    stack = [1]

    # compute xor distances
    while stack:
        u = stack.pop()
        for v, w in g[u]:
            if dist[v] == -1:
                dist[v] = dist[u] ^ w
                stack.append(v)

    MOD = 10**9 + 7
    from collections import Counter

    cnt = Counter()

    # process edges incident to 1
    for a, b, w in edges:
        if a == 1:
            val = dist[b] ^ w
            cnt[val] += 1
        elif b == 1:
            val = dist[a] ^ w
            cnt[val] += 1

    ans = 1
    for k in cnt.values():
        ans = (ans * (k + 1)) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```DFS 计算相对于顶点 1 的 XOR 势，这是有效的，因为每个边约束在 XOR 传播下都是一致的。 关键的微妙之处在于，我们永远不需要显式地推理图中其他地方的循环，因为它们的效果已经编码在 dist 值的一致性中。 

每个与 1 相邻的边都被简化为单个整数签名。 最后的乘法步骤编码了这样一个事实：每个签名类都提供独立的选择：不选择任何一个或从该类中恰好选择一个边缘。 

由于该图是无向的，因此该实现会仔细处理与 1 相关的边的两个方向。 计数器确保分组稳定高效。
