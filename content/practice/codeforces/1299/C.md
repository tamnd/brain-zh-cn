 ## 解决方案
 ## 问题理解

 我们得到了一系列排成一行的水量。 一次操作允许我们选择任何连续的段，并用平均值替换该段中的每个值。 此操作可以在任何段上重复任意次数。 

目标不是最大化或最小化总和，而是将数组重塑为字典顺序上最小的可能最终配置。 这意味着我们主要关心的是使第一个元素尽可能小，然后是第二个元素，依此类推，在每个最终值必须通过重复段平均来实现的约束下。

 一个关键的观察结果是，该操作不会改变它所涉及的任何段的总和，只是均匀地重新分配它。 因此，问题在于决定如何划分和合并相邻段，以便较早的位置获得尽可能小的值，即使这会迫使后面的位置进行补偿。

 约束达到 n = 10^6，这立即排除了任何考虑所有子分段或重复重新计算最佳合并的 O(n²) 方法。 即使是 O(n log n) 的解决方案也必须非常小心，因为每个元素都应该被处理恒定的次数。 

当局部决策影响全局结构时，就会出现微妙的边缘情况。 例如，在像 [10, 1, 1, 10] 这样的数组中，贪婪的“仅在本地有帮助时才合并”策略可能会失败，因为将稍大的前缀与后面的小块合并可以比预期减少更多的早期平均值。 该操作强烈耦合段，因此如果没有单调结构，局部最优性是不可靠的。 

## 方法

 一个蛮力的想法是模拟所有可能的段合并。 在任何阶段，我们都可以选择一个段 [l, r]，用它的平均值替换它，然后继续，直到没有操作改善字典顺序。 然而，段选择的数量是 O(n²)，并且操作序列可能很长。 即使修剪相同的状态也无济于事，因为中间数组是实值并且几乎都是不同的。 这很快就变得不可行。 

关键的结构洞察力是扭转视角。 我们不考虑任意段操作，而是考虑最终数组的外观。 假设我们决定最终答案中从 l 到 r 的位置是相等的。 这总是可以通过将该段重复合并到单个平均块中来实现。 因此，最终的数组实际上是将原始数组划分为连续的块，其中每个块都被其平均值替换。 

现在字典序约束给出了方向。 我们希望早期头寸尽可能小，因此只要这样做会降低或不增加平均值，我们就希望尽可能向右扩展区块。 如果延长一个区块会降低其平均值，那么我们显然应该延长它，因为这会改善较早的位置。 如果扩展增加了平均值，我们必须仔细决定：有时扩展仍然是最佳的，因为按字典顺序减少较早的值可能比增加较晚的值更重要。 

这导致了一个标准的贪婪合并结构：维护一堆段，每个段都有总和和长度，代表当前分区。 当新元素到达时，我们将其视为新段，然后反复检查合并最后两个段是否以保留最佳词典结构的方式提高平均值。 合并条件简化为比较平均值，并且由于平均值在合并下表现单调，因此每个段最多被推送和弹出一次。 

这将问题简化为带有基于堆栈的加权块合并的线性扫描。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | Brute Force（分段模拟）| 指数| O(n²) 状态 | 太慢了|
 | 最优（加权块堆栈）| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们维护一个堆栈，其中每个元素代表一个块：其总和及其长度。 该块的价值是其平均值。 

1. 从空堆栈开始。 
2. 从左到右迭代数组，将每个元素视为一个新块，其总和等于其值且长度为 1。这表示最初每个元素都是其自己的段。 
3. 将新块压入堆栈。 
4. 虽然堆栈至少有两个块，但考虑最后两个块 A 和 B。计算它们的平均值。 如果合并它们可以改善结构，请将它们合并为一个具有组合总和和长度的块。 

合并决策基于确保块平均序列在最优构造中保持不递减。 如果前一个块的平均值高于当前块，则合并它们会创建一个更好地遵循字典最小化的平均段。 
5. 用合并的块替换最后两个块，并重复步骤 4，直到无法进一步合并为止。 
6. 处理完所有元素后，通过用平均值填充块中的每个位置，将每个块扩展回其组成位置。 

其原理与单调不变量有关：每次迭代后，堆栈都会维护其平均值从左到右按非递减顺序排列的块。 如果违反了这一点，则较早的块大于较晚的块意味​​着通过合并将质量向右移动将减少较早的词典位置，这总是有益的。 因为合并保留了总和并减少了边界数量，所以我们永远不会因为立即崩溃此类反转而失去最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(float, input().split()))

# each element: [sum, length]
stack = []

for x in a:
    stack.append([x, 1.0])

    while len(stack) >= 2:
        s2, l2 = stack[-1]
        s1, l1 = stack[-2]

        # compare averages without division instability
        if s1 * l2 > s2 * l1:
            # merge
            stack[-2] = [s1 + s2, l1 + l2]
            stack.pop()
        else:
            break

res = []
for s, l in stack:
    avg = s / l
    res.extend([avg] * int(l))

print("\n".join(f"{x:.10f}" for x in res))
```该实现将每个段保持为一对总和和长度，以避免比较期间浮点不稳定。 合并条件被交叉相乘以保持精度。 

重建步骤将每个块扩展为相同的值。 这是有效的，因为问题中的每个操作都会在所选段内强制执行一致性，因此最终结构在发现的块上必然是分段常数。 

一个微妙的实现细节是仅对最终输出使用浮点算术，而所有结构决策都是使用总和和长度的整数比较来完成的。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个元素被推送一次并最多合并一次 |
 | 空间| O(n) | 堆栈最多存储 n 个块 |

 线性复杂度是必要的，因为输入大小达到一百万个元素。 任何重复访问段的解决方案都会超出时间限制，而这种方法可确保每个元素的摊销恒定工作量。

 ## 边缘情况

 关键的边缘情况是早期值大于后来值，例如 [3, 2, 1]。 天真的贪婪策略可能会避免合并，因为它看到本地平均值不断增加，但最佳词典结果是完全合并到 [2, 2, 2] 中。 该算法通过连续比较相邻块平均值并在存在反转时进行合并来处理此问题。 

另一个边缘情况是像 [5, 5, 5, 5] 这样的统一数组，其中每次合并都是中性的。 该不变量确保不会发生不必要的合并，因为平均值相等，因此除非需要，否则不等式检查可以防止折叠所有内容。 

第三种情况是交替高值和低值，其中只有全部或部分前缀合并是最佳的。 堆栈机制保证任何有益的远程合并都会通过重复的本地合并出现，从而确保全局最优性，而无需显式测试长段。
