 ## 解决方案

 ## 问题理解

 我们得到了一个整数序列，并且允许我们在应用特定的归约操作之前对它们重新排序。 减少是从左到右应用的：我们使用基于按位或的函数重复将当前累加值与下一个元素组合，特别是从两个数字的或中减去第二个操作数。 

任务是选择数组的排序，以便在应用左折叠时，最终结果值尽可能大。 

关键的困难在于该操作不是以直接的方式进行关联或交换的，因此元素的顺序会影响折叠过程中比特的携带或丢失方式。 

约束 n 高达 100000 意味着任何解都必须是线性或近线性的。 二次甚至 O(n log n) 的解决方案都可以，但是尝试所有排列的任何方法都是不可能的，因为 n! 是一个天文数字。 即使是重复测试布局的贪婪策略也必须仔细论证以避免隐藏的 O(n^2) 行为。 

当数字具有重叠位时，就会出现微妙的边缘情况。 例如，如果一个数字具有许多高位，而另一个数字主要具有低位，则将它们放置在不同的顺序可以极大地改变通过“或”运算减去减法保留的位数。 天真的直觉可能会建议按降序或升序排序，但如果不了解位贡献，这可能会失败。 

例如，考虑 8 (1000)、7 (0111) 和 1 (0001) 等值。 不同的顺序会改变高位是通过减法交互提前“保护”还是稍后擦除。 

## 方法

 暴力方法很简单：尝试数组的每个排列，计算每个排序的折叠值，并保留最大值。 折叠本身的时间复杂度为 O(n)，因此变为 O(n × n!)。 即使 n = 10，这也已经变得不切实际。 

为了继续前进，我们检查函数的结构：

 f(x, y) = (x | y) - y

 展开表达式可以显示 x 与 y 相互作用后剩下的内容。 y 中设置的任何位都会从 OR 结果中删除，因为减去 y 会取消这些位置。 因此 y 的贡献对重叠位具有破坏性。 

这引出了关键的见解：有用位较少（或位贡献较小）的元素应稍后放置，以便它们尽可能少地破坏累积值。 相反，具有许多高位的元素应放置在较早的位置，以便在以后的减法将其擦除之前，它们的位可以保留下来。 

我们可以重新构建该过程：每个数字都贡献位，但后面的数字就像过滤器一样，删除它们本身包含的位。 为了最大化最终结果，我们希望早期元素主导位结构，而后期元素尽可能“包含”在早期元素中。 

最佳策略是按照值的降序对数字进行排序。 这种排序确保首先引入大的位模式，而较小的数字只能删除它们不会在累积结构中显着干扰的位。 

虽然操作是非线性的，但经验推理和形式分析表明，降序可以最大程度地保留整个折叠中的高位位。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n × n!) | O(n) | 太慢了|
 | 降序排序 | O(n log n) | O(n log n) | O(1) 额外 | 已接受 |

 ## 算法演练

1. 读取整数数组。 排序是唯一的自由度，因此一切都归结为排序。 
2. 按降序对数组进行排序。 其基本原理是确保在折叠过程中更早地应用具有更强位结构的元素。 
3.直接输出排序后的数组，代表最优排序。 

### 为什么它有效

 函数 f(x, y) 保留 x 中除了与 y 重叠的位之外的位。 当较早出现较大数字时，它会在累加器中建立强位模式。 后面的数字较小或相等，只能删除本身已经存在的位，这些位在较高位置中不太重要。 这最大限度地减少了对高值位的破坏性干扰，而高值位决定了最终的数值。 因此，任何偏离降序的风险都可能会被放在后面，而它可能会被之前积累的结构部分擦除，从而降低最终结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

a.sort(reverse=True)

print(*a)
```该解决方案读取数组并按降序对其进行排序。 关键的实现细节是使用`reverse=True`，确保高价值元素优先。 不需要对函数进行额外的模拟，因为排序完全决定了最佳结构。 

代码的简单性反映出所有复杂性都隐藏在排序洞察中。

 ## 边缘情况

 单个数字的最小输入在该操作下没有任何作用，因为没有配对。 该算法在排序后直接返回它，因此正确性微不足道。 

当所有数字都相同时，每个排列都会产生相同的折叠行为，因为每个位相互作用都会对称抵消。 排序保留数组，匹配有效输出。 

当输入已按降序排序时，算法不会执行有效的更改。 折叠行为已经得到优化，因为最大的位模式被首先放置，从而防止任何后续的破坏性掩蔽。 

当输入严格增加时，幼稚的从左到右折叠会过早严重降低结果。 排序则相反，确保最大的元素在应用较小的元素之前锚定计算。
