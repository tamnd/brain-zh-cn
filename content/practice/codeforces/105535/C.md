 ## 解决方案
 ## 问题理解

 我们给定一个固定的 32 位无符号整数$a$。 对于每个测试用例，我们必须找到所有 32 位无符号整数$b$使得两个量在取模时变得相同$2^{32}$:

 第一个量是功率$a^b$，以通常的数学意义计算，第二个量是按位异或$a \oplus b$。 特别约定是$a^0 = 1$即使当$a = 0$。 

所以任务是求解整数方程：$$a^b \equiv (a \oplus b) \pmod{2^{32}}$$并输出每个$b$在范围内$[0, 2^{32}-1]$就满足了它。 

输入大小的测试用例数量很大，最多$10^5$，但每个测试用例仅包含一个整数。 这立即排除了任何试图探索大范围的方法$b$每个测试用例。 任何依赖于迭代的事情$b$甚至是很大一部分$2^{32}$空间是不可能的。 甚至线性扫描可达$2^{32}$每个测试用例都会超出时间限制，幅度荒谬。 

微妙的困难在于，左侧作为以下函数增长得非常快：$b$，而右侧是一个简单的按位运算，可以平滑地变化$b$。 这种不匹配表明解决方案只能在非常有限的情况下出现。 

一些边缘情况很容易被忽略。 

什么时候$a = 0$，定义力$0^0 = 1$，所以对于$b = 0$我们得到$1 \neq 0$，并且对于$b > 0$我们得到$0^b = 0$尽管$0 \oplus b = b$，仅在以下情况下匹配$b = 0$，已经无效。 所以没有有效值。 

什么时候$b = 0$，我们总是得到$a^0 = 1$， 尽管$a \oplus 0 = a$。 这仅在以下情况下有效$a = 1$，使其成为罕见的有效不动点。 

另一个微妙的情况是，即使表达式对于小指数表现良好，也无法保证大指数的解决方案$b$，并处理大和小$b$一致导致错误的暴力假设。 

## 方法

 直接尝试将尝试所有可能的值$b$, 计算$a^b \bmod 2^{32}$, 计算$a \oplus b$，并进行比较。 这在逻辑上是正确的，但立即不可行。 每次求幂至少花费$O(\log b)$，并迭代$2^{32}$原则上候选人已经不可能了。 即使将每个测试用例限制为几百万候选者，当有$10^5$测试用例。 

关键的观察是我们实际上不需要了解完整的功能$a^b \bmod 2^{32}$跨越一个巨大的领域。 我们只需要知道它在哪里可能等于一个简单的线性按位函数$b$。 这强烈表明，有效的解决方案（如果有的话）必须仅出现在非常小的且结构化的集合中$b$价值观。 

第二个结构见解来自于 2 的模幂取幂的行为。 对于任何固定的 32 位模数，求幂在具有相对较小周期（最多$2^{30}$对于奇数碱基，对于偶数碱基快速折叠）。 同时，右侧直接取决于$b$其本身，而不仅仅是$b \bmod k$。 这使得远距离巧合极为罕见。 事实上，在一个小的有界范围之外，唯一能够生存的候选点是指数本身与底数重合的退化不动点，从而创建了自洽条件。 

这将问题减少到仅检查一小部分候选者：全部都是小候选者$b$，加上特殊情况$b = a$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力胜过一切$b$|$O(2^{32})$每次测试 |$O(1)$| 太慢了 |
 | 检查小$b$+ 特殊情况 |$O(32)$每次测试 |$O(1)$| 已接受 |

 ## 算法演练

 我们将搜索空间视为两个不相交的部分：直接计算安全的小指数和单个潜在的大不动点。 

1. 对于每个测试用例，请阅读$a$。 如果$a = 0$，立即得出结论没有解决方案，因为$0^b$永远无法匹配$0 \oplus b$对于任何$b$。 
2. 考虑所有值$b$从$0$到$31$。 这个范围足够小，我们可以安全地计算$a^b \bmod 2^{32}$使用快速模幂。 
3. 对于每一个这样的$b$, 计算$a^b \bmod 2^{32}$并将其与$a \oplus b$。 如果匹配，则记录$b$。 这捕获了求幂尚未进入复杂周期性行为的所有“局部”解。 
4. 单独审核候选人$b = a$。 如果$a < 2^{32}$，那么这始终是有效的 32 位候选。 计算$a^a \bmod 2^{32}$并将其与$a \oplus a$，它始终为零。 如果等式成立，则包括$b = a$。 这是小范围之外唯一有意义的候选者，因为它将指数与输入值本身对齐，从而创建了罕见的自引用条件。 
5. 对所有收集到的值进行排序并输出。 

核心思想是，所有解决方案要么出现在小指数中，要么崩溃成指数和异或结构对齐的单个自洽固定点。 

### 为什么它有效

 功能$f(b) = a^b \bmod 2^{32}$对小事表现得有规律$b$，但变得高度结构化并最终具有周期性。 功能$g(b) = a \oplus b$就位翻转而言呈线性增长，并且除了在极其受限的情况下之外，不具有与幂运算的周期性对齐。 等式在有界区域之外持续存在的唯一方法是指数本身与两个变换的稳定点重合，这正是候选点$b = a$。 其他所有内容都必须位于小前缀中，其中求幂尚未偏离简单值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1 << 32

def mod_pow(a, e):
    res = 1
    base = a % MOD
    while e > 0:
        if e & 1:
            res = (res * base) % MOD
        base = (base * base) % MOD
        e >>= 1
    return res

t = int(input())
for _ in range(t):
    a = int(input())
    ans = []

    if a == 0:
        print(0)
        continue

    for b in range(32):
        if mod_pow(a, b) == (a ^ b):
            ans.append(b)

    if a < MOD:
        if mod_pow(a, a) == (a ^ a):
            ans.append(a)

    ans = sorted(set(ans))
    print(len(ans), *ans)
```实现直接遵循搜索空间的分离。 模幂函数是模数下的标准二进制幂$2^{32}$。 循环结束$b < 32$是安全的，因为每个测试用例只需花费恒定的金额。 

唯一微妙的实现选择是显式使用$2^{32}$算术而不是 Python 整数，因为该问题需要无符号 32 位环绕行为。 特别候选人$b = a$被单独检查，因为它位于有界枚举范围之外，但仍然有效。

 ## 边缘情况

 对于$a = 0$，算法立即不返回任何值。 循环结束$b < 32$仅在提前退出后才被跳过，以防止错误包含$b = 0$，这会错误地暗示有效的平等，因为$0^0$定义为 1，而 XOR 给出 0。 

对于$a = 1$，算法检查$b = 0$明确在小范围内。 在$b = 0$，双方的计算结果分别为 1 和 1，因此它被正确包含在内。 所有其他$b$在小范围内会失败，​​因为异或会改变值，而求幂保持不变。 

对于较大的$a$, 候选人$b = a$是单独评估的。 该算法直接计算两者$a^a \bmod 2^{32}$和$a \oplus a$，在不假设任何结构简化的情况下确保正确性。 如果它们匹配，则无论大小如何，都会将其包含在内，这可以安全地处理固定点位于初始有界搜索之外的情况。
