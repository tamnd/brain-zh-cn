 ## 解决方案
 ## 问题理解

 我们收到了一项调查，其中一些人已经回答了，他们的答案被总结为每种语言的计数。 受访者总数最终固定为 N，但只知道这些回复的一部分。 剩下的人可以选择任何语言，包括尚未出现的全新语言。 

收集完所有 N 个答案后，每种语言都会报告为 N 的百分比，并且每个百分比都会四舍五入到最接近的整数，并向上舍入。 最终报告的结果是所有语言的这些四舍五入百分比的总和。 

任务不是确定可能的结果，而是假设我们可以敌对地分配剩余的响应，以最大化四舍五入百分比的总和。 

关键输出是分配所有剩余的 N 减去 sum(Ci) 票后的最大可能总和。 

这些限制以非常具体的方式发挥作用。 当 N 达到 10^5 时，任何试图模拟所有可能的分配或迭代剩余人员的所有分布的解决方案都是不可能的。 即使是像尝试各种方法跨语言分配剩余人员这样的事情本质上也是指数级的，并且会立即被排除。 相反，我们必须推理四舍五入作为计数函数的行为。 

舍入会出现一个微妙的问题。 由于每种语言都是独立舍入的，因此投票计数的微小变化可能会使语言跨越多个舍入阈值。 例如，4/10 = 40% 的语言会舍入到 40，但 5/10 = 50% 会跳跃到 50，这是一个很大的离散增益。 整个问题在于如何最佳地利用这些阈值交叉点。 

一个常见的失败案例是假设将所有剩余投票给予现有语言始终是最佳的。 例如，如果计数为 [1, 1]，N = 3，则可以将最后一票分配给一种语言，给出 [2, 1] 和百分比 67 和 33，总和为 100。但是将其分配为新语言给出 [1, 1, 1]，产生 33 + 33 + 33 = 99。这里它有效，但在其他配置中，分割成新语言可能会增加总和，因为舍入是非线性相互作用的 与分母。 

另一种失败模式是将百分比视为连续的，并尝试通过边际增益进行贪婪分配，而不跟踪精确的舍入阈值。 由于舍入引入了分段常数行为，因此边际收益不是线性或平滑的。 

## 方法

 强力方法将尝试将剩余的每一票分配到现有语言或新语言中，重新计算最终百分比，并评估四舍五入的总和。 如果还有 R 票剩余，L 种现有语言，则每票有 (L + R) 个选择，所以这是 (L + R)^R，即使对于 20 左右的 R 也是完全不可行的。 

解锁解决方案的结构是分离语言并根据对最终舍入总和的边际贡献进行思考。 每种语言贡献的值等于 round(100 * Ci / N)。 我们希望在分配额外选票后最大化这些贡献的总和。 

我们不考虑任务，而是考虑每增加一票可以增加多少单一语言的整体贡献。 每种语言的贡献仅在其分数跨越舍入边界时才会改变。 因此，对于每种语言，我们可以计算将其舍入百分比增加 1 个单位所需的额外投票的“成本”，并且“收益”在最终总和中始终为 +1。 

此外，新语言很重要：引入具有 k 票的新语言可提供贡献轮（100 * k / N）。 由于投票稀缺，最佳构造往往要么创建许多小型语言，要么将现有语言改进到下一个舍入阈值。

这将问题简化为将剩余选票贪婪地分配给“有益的升级”，每次升级都有一个成本（所需的选票数量）和一个值（总舍入总和增加 1）。 我们反复选择最便宜的升级，直到选票用完为止。 

关键的见解是每种语言的舍入值仅增加 O(N) 倍，并且我们永远不需要探索所有中间分配，只需要探索下一个阈值转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 剩余票数呈指数增长 | O(N) | 太慢了 |
 | 最优（贪婪阈值模拟）| O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 我们将问题分为两个阶段：处理现有语言和通过新语言处理未使用的投票。 

1. 首先计算剩余票数，R = N − sum(Ci)。 这些是我们可以分配的资源。 
2. 计算每种现有语言的当前贡献为其四舍五入的百分比。 这给出了始终包含在内的基线分数。 
3. 对于每种现有语言，分析需要多少额外投票才能将其舍入百分比精确增加 1。这是通过找到最小的 x 使得舍入 100 * (Ci + x) / N 增加来完成的。 

我们关注“下一次增加”而不是任意增加的原因是，每个中间状态都是无关紧要的，除非它改变舍入值。 

1. 对于每一个这样的改进，我们记录一对（成本，增益 = 1），这意味着我们花费成本投票将最终答案增加 1。 
2. 我们将所有这些候选改进推入按成本排序的最小堆中。 
3. 虽然我们还有剩余选票，但我们反复采取最便宜的改进。 如果其成本 ≤ R，我们应用它：从 R 中减去成本，将答案加 1，然后重新计算该语言的下一个改进并将其推回堆中。 

这是有效的，因为每次增加之后，该语言可能需要不同数量的票数来进行下一次舍入跳跃。 

1. 在用尽有用的升级后，所有剩余的选票将分配给新的语言。 每种新语言在尽可能小的时候会发挥最佳作用，因为舍入函数在小尺度上是凹的。 我们逐一模拟创建语言，直到投票结束，始终选择每种语言大小的最佳边际收益。 

正确性来自于这样一个事实：每个决策都被简化为本地“下一个阈值交叉”，并且对于某些语言来说，没有跳过的中间分配可以产生比下一个可用阈值更好的边际改进。 

### 为什么它有效

 舍入函数将每种语言的贡献划分为离散的高原。 在每个平台内，增加选票的效果为零； 只有进入下一个高原才重要。 因此，每个有益的行动都可以表示为具有明确成本的相邻高原之间的跳跃。 由于每次跳跃都会产生相同的值 (+1)，因此最佳策略始终是首先采用最便宜的可用跳跃。 这是针对成本递增事件的经典贪婪问题，堆确保我们始终选择最佳的下一个改进。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def rounded_percent(x, n):
    return (200 * x + n) // (2 * n)

def next_threshold(ci, n):
    # find smallest x such that rounded(ci+x) > rounded(ci)
    cur = rounded_percent(ci, n)
    lo = 0
    hi = n
    while lo < hi:
        mid = (lo + hi) // 2
        if rounded_percent(ci + mid, n) > cur:
            hi = mid
        else:
            lo = mid + 1
    return lo

def solve():
    t = int(input())
    for tc in range(1, t + 1):
        n, l = map(int, input().split())
        arr = list(map(int, input().split()))
        
        used = sum(arr)
        r = n - used

        heap = []
        ans = 0

        for c in arr:
            ans += rounded_percent(c, n)
            cost = next_threshold(c, n)
            heapq.heappush(heap, (cost, c))

        # helper to recompute next jump
        def push_next(ci):
            cost = next_threshold(ci, n)
            heapq.heappush(heap, (cost, ci))

        while heap and r > 0:
            cost, ci = heapq.heappop(heap)
            if cost == 0:
                continue
            if cost <= r:
                r -= cost
                ci += cost
                ans += 1
                push_next(ci)
            else:
                break

        # remaining votes: each new language contributes minimally 0 or 1 depending on rounding
        # best is to create single-vote languages while beneficial
        while r > 0:
            ci = 1
            gain = rounded_percent(ci, n)
            if gain == 0:
                break
            ans += gain
            r -= 1

        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    solve()
```该实现跟踪每种语言的当前计数并重复计算达到下一个舍入边界的成本。 堆确保我们总是选择最便宜的可用改进。 每次改进后，该语言都会以其更新后的状态重新插入。 

最后一个循环仅在新语言做出积极贡献时才通过创建新语言来处理剩余选票； 否则，增加语言不会增加总金额。 

一个微妙的地方是，舍入公式是使用整数运算来实现的，以避免浮点错误。 我们通过仔细缩放来计算 100 * Ci / N，并进行四舍五入，以便正确处理 0.5 处的关系。

 ## 边缘情况

 当所有语言已经完全位于舍入边界时，就会出现一种边缘情况。 在这种情况下，添加投票可能不会立即增加任何舍入值。 该算法会处理此问题，因为 next_threshold 返回第一个有意义的跳转，并且会跳过零成本或无改进的转换。 

另一种情况是当创建新语言变得最佳时。 如果所有现有语言的升级成本太高，堆会提前清空，剩余的投票将单独处理。 该算法正确地避免了在无益的分裂上浪费选票。 

最后一种情况是 N 很小时且舍入效应极端。 例如，N = 3，计数为 [1]。 在这里，剩下的一票可以完全改变舍入的结构。 堆正确评估升级现有语言或创建新语言是否会产生更高的边际收益，从而确保最佳分配。
