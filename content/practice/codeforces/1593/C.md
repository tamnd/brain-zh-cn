 ## 解决方案
 ## 问题理解

 我们得到了一条包含三种类型实体的线段：从位置 0 开始的一只猫、位置 n 处的一个洞以及严格位于它们之间的几只老鼠。 时间以离散的秒数前进。 每一秒分为两个动作：首先我们选择一只老鼠并将其向右移动一步，然后猫向右移动一步。 如果老鼠在移动过程中到达洞口，它会立即安全并不再参与。 如果猫在移动后落在有一只或多只老鼠的位置，这些老鼠就会被吃掉。 

任务是选择每秒移动哪只老鼠，以便在移动后与猫共享位置之前最大限度地增加到达洞口的老鼠数量。 

重新解释这一点的一个有用方法是将每只老鼠视为有一个最后期限：它必须严格在猫到达其位置之前到达位置 n。 然而，与静态截止日期问题不同，我们可以在小鼠之间交错进度，这会产生调度问题而不是直接比较问题。 

约束条件很大：所有测试用例中的小鼠总数最多为 4⋅10^5。 这立即排除了任何二次模拟，即我们对每只小鼠每秒重复模拟。 即使每个测试用例的 O(k^2) 也太慢了。 我们需要更接近 O(k log k) 或 O(k) 的东西。 

一些边缘情况揭示了结构：

 如果所有老鼠一开始都离猫很近，例如 n = 10 且位置为 [1,1,1,1]，那么如果我们反复推进一只老鼠，任何糟糕的调度都可能让猫在任何老鼠到达洞之前在位置 1 捕获所有老鼠。 正确的策略是优先将一些小鼠推得足够远，以便它们“逃离猫的触及窗口”。 

如果所有小鼠都已靠近洞，例如 n = 10 且位置为 [9,9,9]，则只要立即移动至少一只小鼠，任何调度都有效。 限制因素不是小鼠之间的干扰，而是每秒单只小鼠的限制。 

关键的微妙之处在于猫以单位速度确定性地前进并充当移动的截止线。 落后于这个界限的老鼠注定会不可逆转地灭亡。 

## 方法

 直接模拟会尝试每秒建模，贪婪地甚至详尽地选择一只老鼠，更新位置并检查老鼠是否被吃掉或逃脱。 虽然正确，但这种方法从根本上来说太慢了，因为每只小鼠可能需要最多 O(n) 次移动，而我们最多有 4⋅10^5 只小鼠。 

关键的观察是反转视角：我们不考虑绝对空间中的位置，而是考虑“每只老鼠在被抓住之前存活了多少秒”。 从位置 x 开始的老鼠必须在猫到达 x 之前到达 n。 由于猫从 0 开始每秒精确移动一步，因此猫在时间 x 到达位置 x。 这表明鼠标必须在与其起始位置相关的截止日期之前完成其所需的行程。 

然而，老鼠不会连续移动； 每秒只有一只老鼠可以移动，因此老鼠在截止日期之前有效地竞争时间段。 这就变成了一个调度问题：每个鼠标 i 需要一定数量的移动 (n − x_i)，并且它必须在时间 x_i 之前接收到足够的回合。 

重写这个，如果我们设法完全处理它，每只鼠标提供的“利润”为 1，并且有一个大小为 x_i 的约束窗口。 最好的策略是选择在可用窗口内最容易完成的小鼠。 这自然建议按起始位置排序并贪婪地计算可以完成的数量，同时尊重累积时间。

我们按照小鼠与猫的距离递增的顺序（或者等效地递减起始位置）来处理小鼠。 每次我们考虑鼠标时，我们都会尝试为其分配所需的移动次数。 如果在任何时候我们超过了最后期限，我们将根据可行性跟踪相应地停止或跳过。 最终的结构简化为在可行性条件下选择最大前缀。

 | 排序后的贪心调度 | O(k log k) | O(k log k) | O(k) | 已接受 |

 ## 算法演练

 我们将每只老鼠重新解释为需要一定量的处理时间，并且有猫到来所规定的最后期限。 

1. 计算每只老鼠到达洞口所需的时间，即 n − x_i。 这是必须选择移动的次数。 
2. 按小鼠的起始位置降序对它们进行排序。 靠近洞的老鼠会被优先考虑，因为它们的截止日期更紧迫； 拖延它们可能会造成立即损失。 
3. 维护一个运行计数器，表示为我们尝试保存的小鼠分配移动所花费的秒数。 该计数器代表我们日程安排中的全局时间使用情况。 
4. 按排序顺序迭代小鼠。 对于每只鼠标，将其所需的行进时间添加到计数器中。 
5. 如果在猫到达相关边界之前的任何时刻，累积时间超过了可用的安全移动次数，则无法保存该鼠标，并且我们停止增加计数。 
6. 否则，将此鼠标视为已成功调度。 

关键思想是，每只被拯救的老鼠都会消耗时间表中连续的时间块，并且必须保证较早的老鼠（靠近洞）在猫的进展消除其可行性窗口之前完成。 

### 为什么它有效

 在任何时刻，猫都会强制执行单调递增的约束：一旦猫经过这些位置，位置就会永久变得不安全。 这创建了一个结构，其中可行性仅取决于我们是否可以在其隐式截止日期之前为每个选定的鼠标分配足够的早期时隙。 按位置排序可确保我们始终首先考虑限制性最强的情况。 贪婪的积累确保我们永远不会在不适合剩余时间表的鼠标上“浪费”早期时间。 因为每只小鼠都竞争相同的单个单位时间资源，所以最优性降低为在不断增加的约束下用最大数量的非重叠时间需求来填充时间表。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        x = list(map(int, input().split()))

        # sort mice by closeness to hole (largest x first)
        x.sort(reverse=True)

        time_used = 0
        saved = 0

        for xi in x:
            need = n - xi

            if time_used + need <= xi:
                time_used += need
                saved += 1
            else:
                break

        print(saved)

if __name__ == "__main__":
    solve()
```该代码首先对老鼠进行排序，以便首先处理最接近洞的老鼠，因为它们对时间最敏感。 对于每只老鼠，我们计算它需要多少次移动才能到达洞口。 变量`time_used`跟踪我们已经安排的鼠标移动总数。 仅当添加所需的移动仍允许鼠标在猫到达其起始位置之前完成时，我们才接受鼠标。 一旦这种情况失败，就无法拯救更多的小鼠，因为剩余的小鼠受到的限制更少。 

关键的实现细节是不等式`time_used + need <= xi`。 它编码了这样一个事实：分配给老鼠的所有工作都必须在猫到达其起始位置之前发生。

 ## 边缘情况

 位置 1 附近的紧密集群最清楚地暴露了调度约束。 对于像 n = 10 和 x = [1,1,1] 这样的输入，每只鼠标需要 9 次移动，而它们的截止时间为 1，这使得所有的操作都可行，但可能没有一个可行。 该算法在第一次添加后立即检测到不可行性`time_used`，因为即使有一项作业也超出了截止日期条件。 

孔附近的对称情况，例如 x = [n−1, n−1, n−1]，显示相反的行为。 每只老鼠只需要一次移动，而且它们的截止时间足够长，可以在猫到达它们的位置之前安排多次移动。 贪婪累积继续进行而不会违反，确认约束仅在累积工作超过可用安全时间时才绑定。
