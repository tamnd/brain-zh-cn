 ## 解决方案
 ## 问题理解

 给定一个以十进制形式书写的数字，并且允许我们从数字中的任何位置一一删除数字。 每次删除后，剩余的数字都会闭合，并且任何前导零都会自动消失。 该过程一直持续到我们决定停止为止，并且我们希望最终剩余的数字能够被 25 整除，同时仍然为正数。 

以 10 为基数的 25 整除性非常严格：当且仅当一个数字的最后两位数字形成模式 00、25、50 或 75 之一时，该数字才能被 25 整除。这意味着整个问题可以简化为使用删除将数字后缀塑造为这四个结尾之一。 

就测试用例的数量而言，输入大小很大，最多可达 10^4，但每个数字本身都适合有符号的 64 位整数，因此最多 18 位数字。 这立即排除了任何试图模拟所有删除序列或位置子集上的 DP 的方法。 即使每个测试用例的二次解决方案都可以，但任何超过数字的指数都是不必要且不安全的。 

一个微妙的问题是与前导零的相互作用。 删除数字可能会导致中间或最终结果，例如“050”或“005”，然后将其视为“50”或“5”。 这很重要，因为它改变了我们解释“保留两位数字作为后缀”的方式：我们有效地按顺序选择两位数字，不一定是相邻的，并且其他所有内容都被删除。 

一个天真的错误是认为我们必须保留连续的子串。 例如，在 2050047 中，人们可能会错误地将注意力限制在 20、05、50、04、47 等子字符串上，但有效的结构允许完全跳过数字，因此非连续选择占主导地位。 

## 方法

 蛮力的想法是尝试所有删除数字的方法，直到达到有效数字。 对于 18 位数字，每个数字可以保留或删除，因此有 2^18 种可能性，每个测试用例大约有 260,000 个子集。 对于 10^4 的测试用例，这是不可行的。 更糟糕的是，我们仍然需要验证每个子集排序并计算结果数字。 

关键的观察是我们不关心整个数字，只关心删除后的最后两位数字。 任何有效的最终号码完全是通过从原始号码中选择按顺序成为最后两位数字的两位数字来确定的，并确保剩余的前缀（如果有）无关紧要。 

因此，任务变为：对于每个以 {00, 25, 50, 75} 结尾的目标，找到使两位数字按该顺序出现在末尾所需的最小删除次数。 一旦这两个数字被固定，原始字符串中它们之后的所有数字都必须被删除，并且所选数字之间的所有数字也必须被删除。 

我们测试每对位置 (i, j)，其中 i < j，其中数字与目标结尾匹配。 如果我们将它们固定为最后两位数字，则 j 之后的所有数字都将被删除，并且 i 和 j 之间的所有数字（除了 i 和 j 本身）都将被删除。 删除的总数仅取决于我们丢弃的数字数量。 

这减少了检查所有有效对的四个结尾的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集 | O(2^d · d) | O(2^d · d) | O(d) | 太慢了 |
 | 检查数字对 | 每次测试 O(d^2) | O(1) | O(1) | 已接受 |

 由于 d ≤ 18，O(d^2) 是微不足道的。 

## 算法演练

 我们将数字视为一串数字。

1. 对于每个测试用例，读取数字字符串并存储其长度n。 我们将为每个以 00、25、50 和 75 结尾的目标独立计算答案。 
2. 对于固定目标结尾，我们尝试先选择最后一位数字。 我们从右向左扫描并选取数字等于目标第二个数字的每个位置 j。 这是因为 j 必须是保留的最后一位数字，因此 j 右侧的所有内容都将被删除。 
3. 对于每个这样的位置 j，我们搜索有效位置 i < j，其中数字等于目标的第一个数字。 这 i 将是最终数字中的倒数第二位数字。 
4. 对于选定的对 (i, j)，我们按如下方式计算删除。 j 之后的所有数字都被删除，导致 n - 1 - j 删除。 i 和 j 之间的所有数字都被删除，导致 j - i - 1 次删除。 i 之前的所有不属于最终前缀的数字都必须删除，除非我们只计算删除次数，因此总删除次数简化为：

 删除 = (n - 2) - (i + (n - 1 - j))

 但直接思考更简单：保留 i 和 j，因此删除 = n - 2。 

然而，这忽略了排序约束，因此我们正确地解释：我们保留 i 和 j 以及可能形成前缀的较早数字，但由于只有删除很重要，所以正确的计算是：

 删除 = (n - 1 - j) + (j - i - 1) + (i - prefix_kept_count)，但 prefix_kept_count 无关紧要，因为所有保留的数字只有 i 和 j 才能保证后缀有效性。 因此最终的删除是：

 删除 = (n - 1 - j) + (j - i - 1)

 这等于 n - i - 2。 

因此，对于每个有效对，我们评估 n - i - 2。 
5. 我们对所有有效对和所有四个目标结局取最小值。 
6. 输出最小值。 

### 为什么它有效

 任何有效的最终数字必须以 25 后缀的四个倍数之一结尾。 一旦最后两位数字固定下来，剩下的数字就不会影响整除性，所以我们只需要按顺序保留两位数字即可。 每个有效的构造都唯一对应于选择与有效后缀匹配的索引 i < j。 删除的数量仅取决于这些索引距字符串末尾的距离，选择最佳的一对可以最大限度地减少删除。 因为我们检查了所有可能性，所以我们不会错过更好的配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_one(s):
    n = len(s)
    targets = [("0", "0"), ("2", "5"), ("5", "0"), ("7", "5")]
    ans = n  # worst case delete everything except 2 digits

    for a, b in targets:
        best = n
        for j in range(n - 1, -1, -1):
            if s[j] != b:
                continue
            for i in range(j - 1, -1, -1):
                if s[i] == a:
                    # deletions = n - i - 2
                    best = min(best, n - i - 2)
        ans = min(ans, best)

    return ans

def main():
    t = int(input())
    for _ in range(t):
        n = input().strip()
        print(solve_one(n))

if __name__ == "__main__":
    main()
```该解决方案循环遍历所有有效的后缀模式，然后循环遍历结果数字最后一位数字的所有候选位置。 对于每个这样的位置，它向后搜索匹配的前面的数字。 这确保了所选对保持顺序。 删除公式`n - i - 2`之所以有效，是因为除了所选的两位数字及其相对顺序之外的所有内容都被删除了。 

一个常见的实施陷阱是混淆索引并计算相对于末尾而不是相对于保留位置的删除。 最安全的方法始终是考虑“保留哪些索引”，而不是“分段删除多少索引”。

 ## 边缘情况

 常见的边缘情况是有效后缀数字存在但顺序相反。 例如，数字可能在“2”之前包含“5”，但对于“25”目标，我们需要在“5”之前包含“2”。 该算法明确强制执行索引排序 i < j，因此即使两个数字都存在，此类反转对也会被忽略。 

另一个边缘情况是重复的零。 在像 20099050 这样的输入中，多个候选零可以用作后缀数字。 该算法会尝试第二个数字的所有 j 个位置，确保它不会过早做出次优的极右选择。 

最后的边缘情况是当最佳解决方案使用非常接近的数字时，这可以最大限度地减少 i 和 j 之间的删除。 表达式 n - i - 2 自动捕获这一点，因为最大化 i 会直接最小化删除，并且算法自然会为每个 j 首选最右边的有效 i。
