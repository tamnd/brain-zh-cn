 ## 解决方案
 ## 问题理解

 我们在选举中获得了三名候选人，每名候选人都有当前的票数：$a$,$b$， 和$c$。 任务是为每个候选人独立确定他们需要多少额外选票才能确保他们获胜。 获胜者的定义是比其他两名候选人拥有更多的选票。 对于每位候选人，另外两人的选票保持不变； 目标是让该候选人严格领先。 

约束允许最多$10^4$测试用例，投票最高可达$10^9$。 这立即告诉我们，任何迭代潜在额外投票的解决方案都将太慢，因为每个测试用例可能需要数十亿次操作。 我们需要一种方法来以数学方式计算每个候选人在恒定时间内所需的票数。 

当候选人已经拥有相同票数时，就会出现不明显的边缘情况。 例如，如果票数是$a=0, b=0, c=0$，每个候选人只需要一票就能超越其他候选人，而不是零票。 当一名候选人已经比其他候选人拥有更多的选票时，就会发生另一种微妙的情况。 例如，$a=10, b=5, c=5$： 候选人$a$需要零额外票数，而其他人则需要足够多的票数才能超过$a$。 这些案例说明了谨慎处理平等和执行“严格更大”条件的重要性。 

## 方法

 暴力解决方案将模拟为每个候选人增加选票，直到他们严格领先于其他候选人。 对于候选人$a$，你会增加$a$一一直到$a > \max(b, c)$，类似地对于$b$和$c$。 虽然正确，但这需要最多$10^9$在最坏的情况下会增加，并且在大输入时会失败。 

关键的见解是我们不需要模拟。 为了超越其他候选者，我们只需要知道其他两个的当前最大值并计算差异。 对于候选人$a$，所需的最低附加票数为$\max(b, c) - a + 1$，但我们必须将其上限为零，如果$a$已经严格更大了。 这个推理同样适用于$b$和$c$。 这将问题转化为每个测试用例每个候选者的一些算术运算，保证了恒定时间计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(最大(a,b,c)) | O(1) | O(1) | 对于大票来说太慢了 |
 | 最佳 | 每个候选人 O(1)，每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量$t$。 
2. 对于每个测试用例，读取三个整数$a$,$b$,$c$代表选票。 
3. 对于候选人$a$，计算所需的额外票数为$\max(0, \max(b, c) - a + 1)$。 内部最大值找到最强的竞争对手，减去$a$给出间隙，加 1 确保$a$变得严格更大。 使用$\max$零确保我们不会建议投反对票，如果$a$已经领先了。 
4. 对候选人重复相同的计算$b$和$c$。 为了$b$， 使用$\max(a, c) - b + 1$; 为了$c$， 使用$\max(a, b) - c + 1$。 
5. 打印测试用例的三个结果。 

为什么有效：在每一步中，我们都会准确计算每个候选人距离超越当前领导者还有多远。 添加一名即可确保严格的优势。 这种方法保证了正确性，因为它直接执行获胜条件，并且独立于其他候选人的调整，符合问题要求。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, c = map(int, input().split())
    A = max(0, max(b, c) - a + 1)
    B = max(0, max(a, c) - b + 1)
    C = max(0, max(a, b) - c + 1)
    print(A, B, C)
```代码直接遵循算法。 我们使用快速 I/O`sys.stdin.readline`自从$t$可以很大。 计算`max(b, c) - a + 1`执行严格的优势条件。 外层`max(0, …)`确保我们不会为已经领先的候选人返回负数。 该解决方案避免了投票计数的循环，从而防止了大量的性能问题。

 ## 边缘情况

 用于输入`0 0 0`，每个候选人都是平局。 该算法计算其他人的最大值 (0)，减去候选人的选票 (0)，然后加 1，即每个候选人获得 1 票。 由于以下原因，不会返回负数`max(0, …)`包装纸。 用于输入`1000000000 0 0`， 候选人`a`已经领先，所以计算`a`产生 0. 候选者`b`和`c`计算`max(1000000000,0)-0+1 = 1000000001`，正确给出超越所需的票数`a`。 处理所有边缘条件，包括最大投票数和平等性。
