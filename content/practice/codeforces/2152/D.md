 ## 解决方案
 ## 问题理解

 我们得到一个数组，其中每个元素至少从 2 开始，两个玩家重复修改它，直到每个值都变成 1。一个玩家总是通过用其下限值的一半替换所选元素来减少所选元素，而另一个玩家总是将所选元素增加 1，但仅限于仍至少为 2 的元素。 

该过程是一个回合制游戏，波比先移动。 Poby 每次行动时，都会将一个元素减半，将其“推”向 1。 Rekkles 每次行动时，都会通过递增的方式向上“拉动”一个元素，这让 Poby 的工作变得更加困难。 只有当所有条目都变成1时游戏才会停止，分数就是Poby移动的次数。 

每个查询都会给出一个子数组，我们必须计算如果两个玩家都在该子数组上发挥最佳状态，将会发生多少次 Poby 移动。 

约束足够大，以至于预处理后每个查询必须在大致对数或恒定时间内得到回答。 由于元素和查询总数高达 250,000 个，任何游戏模拟都立即变得不可能，因为即使是单个元素也可能需要许多减半步骤，而 Rekkles 可能会干扰每个元素。 这种交互创建了一个动态过程，必须将其简化为每个元素的静态贡献。 

一个幼稚的错误是独立对待每个元素，并假设答案只是“达到 1 的减半次数”的总和。 但这会失败，因为 Rekkles 可以增加值，从而有效地延迟完成。 

例如，如果我们有一个元素 2，Poby 需要一步。 但是，如果元素为 2 并且允许 Rekkles 在 Poby 完成之前不断增加它，则该过程的行为就不像简单的倒计时。 另一个失败案例是假设单调独立：

 输入：```
[2, 2]
```如果独立，答案是 2。但是 Rekkles 可以继续提升一个元素，因此 Poby 被迫在这两个元素上花费额外的减半操作。 

因此，真正的困难在于，操作之间的交互只能通过轮流排序，而不是通过直接耦合。 

## 方法

 蛮力方法准确地模拟了游戏状态。 每个回合都会为当前玩家选择一个最佳动作并更新数组。 Poby 尝试选择最快速减少未来工作的元素，而 Rekkles 则选择最大程度增加未来工作的元素。 这需要维护完整的阵列并反复评估未来的结果。 

每一次操作只会稍微改变一个元素，但操作的数量可能会变得非常大，因为在 Rekkles 的移动下，值可以无限增加。 在最坏的情况下，值会在再次下降之前长时间向上漂移，从而产生长交替序列。 这使得直接模拟在实践中呈指数级增长。 

关键的观察结果是元素永远不会直接相互作用。 唯一的耦合是通过全局回合顺序，因此可以根据每个元素消耗的有效 Poby 操作数量来分析，而 Rekkles 可以延迟这些操作之间的进度。 

对于固定的元素值，我们可以这样解释这个过程：Poby通过重复减半来减少它，但Rekkles在中间插入+1操作，这增加了后面需要的减半次数。 核心见解是，每个元素通过其二进制表示的函数独立地对答案做出贡献：每次 Rekkles 加 1 时，它都可以被认为是传播进位，但仅限于该元素的局部值演化。 

这导致了一种转变：我们不是模拟游戏，而是计算每个元素的权重，该权重等于其二进制结构允许 Rekkles “延迟”减半的次数。 该权重与二进制表示中 1 位的数量成正比。 

因此，范围的最终答案成为对预先计算的每个元素值的范围总和查询。

 | 暴力模拟| 指数| O(n) | 太慢了 |
 | 二进制派生权重的前缀和 | O(n + q) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个元素，计算一个值`w(x)`代表它对 Poby 分数的贡献。 该值是其二进制表示形式中设置的位数。 这捕获了在对抗增量下数字崩溃到 1 之前结构上需要多少个减半阶段。 
2. 在这些值上构建一个前缀和数组，以便可以在 O(1) 内回答任何查询范围和。 
3. 对于每个查询`[l, r]`， 返回`prefix[r] - prefix[l-1]`。 

这样做的原因是，一旦我们认识到 Rekkles 的最佳行为只影响值保持较大的时间，而不影响不同元素之间的交互方式，游戏就会对每个元素进行解耦。 减半过程取决于二进制结构，增量只会改变该结构，而不会将元素耦合在一起。 

### 为什么它有效

 不变的是，每个元素对所需的 Poby 操作总数独立贡献，Rekkles 的最佳策略仅增加该元素所需减半的有效数量，而不会在不同指数之间转移“成本”。 由于没有任何操作会在索引之间移动值，因此总分是对元素进行累加的。 二进制表示决定了一个元素在交替增量压力下达到 1 之前可以存活多少次，从而分解为固定的每个值贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def bitcount(x):
    return x.bit_count()

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i].bit_count()

        for _ in range(q):
            l, r = map(int, input().split())
            out.append(str(pref[r] - pref[l - 1]))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案使用 Python 的内置位计数计算每个元素的二进制权重，然后构建一个前缀和数组，以便在恒定时间内回答每个查询。 关键的实现细节是处理多个测试用例，而无需重新分配大型结构； 每个测试用例都会重建所有内容，以避免遗留错误。 

前缀数组是 1 索引的，这可以避免减去范围时出现差一错误。 每个查询直接减去累加和，确保 O(1) 检索。

 ## 边缘情况

 最小数组，例如`[2]`产生单个贡献 1，因为二进制表示有一个设置位。 该算法可以处理此问题，因为前缀数组是使用单个增量构造的，并且查询直接解析为该值。 

对于像这样的均匀数组`[2,2,2,2]`，每个元素的贡献相等，并且任何范围查询都与其长度成正比。 即使所有值都相同，前缀和结构也能保证正确性。 

对于像这样的大值`2^30`，位计数仍然为 1，因此即使极端的量级也不会扭曲结果。 计算保持稳定，因为它仅取决于二进制结构，而不取决于数字大小。
