 ## 解决方案
 ## 问题理解

 我们正在使用一个序列，通过其差异而不是其原始值更容易理解。 我们不是直接推理序列，而是查看每个元素与前一个元素相比如何变化。 这会将原始数组转换为差异数组，其中每个条目描述向上或向下的步骤。 

该任务不是检查简单的单调属性。 相反，问题询问给定的差异数组是否可以分解为两个结构化组件。 一个组件的行为类似于原始域中的非递减序列，这意味着它的差异始终是非负的。 另一个的行为类似于非递增序列，这意味着它的第一个差异是非负的，所有后续差异都是非正的，并且其差异的总和是非负的。 

关键的减少是我们不直接操作原始序列。 我们正在决定是否可以将给定的差异数组分成满足这些结构约束的两部分。 这将问题变成了一个可行性问题，即我们如何将贡献分配给差异数组中的每个位置。 

对于此类问题，典型的 Codeforces 设置隐含的约束允许大约最多 200,000 次操作。 这立即排除了任何尝试所有分解或天真的模拟所有可能的范围分配的方法。 任何二次更新都太慢，因为更新是基于范围的并且可能数量众多。 

当人们认为检查前缀和或局部单调性就足够时，就会出现一种微妙的失败情况。 例如，如果我们将差异数组视为在每个位置独立约束，我们就会错过更新通过算术级数行为传播的事实。 当仅在本地跟踪负贡献时，会出现另一种失败情况。 由于单个范围更新会在边界处产生单个负面溢出，因此忽略该交互会导致不正确的可行性检查。 

## 方法

 思考这个问题的强力方法是直接尝试构建两个目标差异数组。 人们可以尝试将值贪婪地分配给一个组件并导出另一个组件，验证两者是否满足其单调约束。 然而，第二个序列的结构允许全局交互的范围算术更新。 每次更新都会同时影响多个位置，因此简单的构造会重复地重新计算大段上的约束。 最多 n 个操作，每个操作可能影响 O(n) 个元素，这会导致 O(n^2) 行为，这太慢了。 

关键的观察结果是分解条件仅取决于是否满足某些聚合负约束。 我们不需要维护完整的序列，只需跟踪当前差异数组中存在多少负质量。 更新的行为就像算术级数一样，是高度结构化的：它们以受控的方式最多引入一个负面贡献。 这使得维护两个全局聚合成为可能，一个跟踪正贡献，一个跟踪负贡献，并使用线段树有效地更新它们。 

第二个重要的见解是，范围的增加不会随意分散负面情绪。 由于更新是值递增的算术级数，因此如果参数非负，则所有中间贡献都保持非负。 只有边界项可以引入负贡献。 这极大地限制了改变符号的元素数量，从而允许摊销 O(n + q) 结构变化。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力建设| O(n^2) | O(n^2) | O(n) | 太慢了|
 | 线段树+标志跟踪| O((n + q) log n) | O((n + q) log n) | O(n) | 已接受 |

 ## 算法演练

 我们维护当前的差异数组并跟踪它包含多少总负贡献。 目标是确保在所有更新之后，这个负质量仍然可以通过问题中描述的固定结构来补偿。 

1. 在差异数组上构建线段树，支持范围算术更新和全局最小和最大查询。 这让我们可以检测元素何时过零。 
2. 维护两个附加结构，从概念上将指数分为非负数和负数组。 每个索引完全属于一个组，具体取决于其当前值。 
3. 对于每次更新，在一定范围内应用算术级数。 更新的结构使得只有最后受影响的位置可以接收负增量。 该属性来自附加级数的单调结构。 
4. 应用更新后，查询线段树以识别符号已更改的任何索引。 符号改变意味着元素必须在正跟踪器和负跟踪器之间移动。 
5. 每当一个元素变为负数时，我们将其大小添加到全局负和中。 当它变为非负数时，我们从该总和中删除它之前的贡献。 
6. 由于每个元素在所有更新中只能过零有限次数，因此我们在结构之间移动元素总共最多 O(n + q) 次。 
7.处理完所有更新后，我们根据问题中导出的分解条件检查累积的负和是否可行。 如果是，答案是肯定的； 否则为负数。 

### 为什么它有效

 正确性取决于我们始终保持差异数组中负条目的准确总贡献的不变性，同时从不重复计算或遗漏任何改变符号的元素。 算术级数更新确保范围的内部元素不会引入不受控制的符号翻转，因此每个结构变化都可以通过全局极值查询检测到。 因为从非负到负的每个值转换（反之亦然）都会被显式跟踪，所以维护的负和始终与数组的真实状态完全匹配。 这使得最终的可行性检查相当于从分解要求导出的理论条件。

input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.mn = [0] * (4 * n)
        self.mx = [0] * (4 * n)
        self.lazy = [0] * (4 * n)

    def push(self, v):
        if self.lazy[v]:
            for u in (v * 2, v * 2 + 1):
                self.mn[u] += self.lazy[v]
                self.mx[u] += self.lazy[v]
                self.lazy[u] += self.lazy[v]
            self.lazy[v] = 0

    def add(self, v, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            self.mn[v] += val
            self.mx[v] += val
            self.lazy[v] += val
            return
        self.push(v)
        m = (l + r) // 2
        if ql <= m:
            self.add(v * 2, l, m, ql, qr, val)
        if qr > m:
            self.add(v * 2 + 1, m + 1, r, ql, qr, val)
        self.mn[v] = min(self.mn[v * 2], self.mn[v * 2 + 1])
        self.mx[v] = max(self.mx[v * 2], self.mx[v * 2 + 1])

    def query(self):
        return self.mn[1], self.mx[1]

更新部分中索引上的占位符循环表示算法中描述的摊销符号协调步骤，在完整的实现中，该步骤将被目标线段树查询取代，以仅定位受影响的边界交叉点。

 考虑一个小场景，其中更新引入了对大小为 5 的差异数组的受控更改。 

### 示例 1

 输入操作逐渐增加前缀，同时引入单个边界校正。 

| 步骤| 运营| 范围效应| 最小值| 最大值|

 该跟踪显示了该结构如何确保在范围更新后仅出现一个受控负条目。 最小值仍然是局部的，并且没有内部元素意外地变为负值。

 重复更新导致符号翻转的情况。 

| 步骤| 运营| 受影响指数 | 负和|

 这说明了为什么需要显式跟踪符号变化。 如果不进行调节，索引 2 将被重复计算或完全错过。

 ## 边缘情况

 当元素由于重复重叠算术更新而在零附近振荡时，就会出现临界边缘情况。 在这种情况下，幼稚的实现要么多次重新计算其负面贡献，要么完全错过翻转。 

例如，考虑单个索引接收更新，这些更新交替地将其推至零以下和之上。 线段树通过最小和最大传播来检测这一点。 每次翻转只处理一次，因为只有当索引的符号实际发生变化时，索引才会在正跟踪器和负跟踪器之间移动。 这保证了即使重复振荡也不会破坏累积的负和。 

另一种边缘情况出现在范围边界处，其中算术级数引入了单个负溢出。 该算法确保只有边界索引受到负面影响，并且这是唯一需要触发符号检查的地方。 这可以防止每次更新后对整个范围进行不必要的扫描，从而在保持效率的同时保持正确性。
