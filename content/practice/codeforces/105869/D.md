 ## 解决方案
 ## 问题理解

 我们正在处理一个过程，其中存在一组从 1 到 n 的整数，并且我们从中随机选择大小为 k 的子集。 从该子集中，我们对最大元素感兴趣。 固定大小 k 的所有子集的随机性是均匀的，因此 {1, 2, ..., n} 的每个 k 元素子集的可能性相同。 

对于从 1 到 n 的每个可能的 k，当我们选择 k 元素子集时，我们会考虑最大元素的期望值。 那么最终感兴趣的数量是所有 k 的这些期望的平均值，这意味着每个子集大小都具有相同的权重。 

输出是单个预期值，该值聚合了所有子集大小的此行为。 

主要困难不是随机性本身，而是以避免枚举子集或模拟任何事物的形式表达期望。 这些约束意味着 n 可能很大，因此任何迭代所有子集甚至子集中所有元素对的方法都是立即不可行的。 n 中的任何二次方都已经太慢了，如果存在多个测试用例，即使每个测试用例进行 O(n^2) 组合推理也是不可接受的。 

一个微妙的边缘情况是 n 非常小时。 当 n 等于 1 时，每个 k 仅有一个子集，并且预期的最大值一般为 1。如果不小心实现涉及调和数的派生公式，则可能会由于被零除或 H1 减 1 样式表达式的错误处理而在此处中断。 

另一个边缘情况是浮点精度。 最终公式涉及调和数，它以对数方式增长，如果不仔细累加或每次查询重复重新计算，浮点数的简单求和可能会失去精度。 

## 方法

 暴力视图从定义开始：对于固定的 k，我们枚举 {1, ..., n} 的所有 k 元素子集，计算每个子集的最大值，并对这些值求平均值。 这在概念上是简单且正确的，因为它直接遵循概率空间。 然而，子集的数量为 C(n, k)，每个子集需要扫描最多 k 个元素才能找到最大值，因此单个 k 的成本已经为 O(C(n, k) · k)。 对所有 k 求和使其具有爆炸性组合，总共以 2^n 个子集的数量级增长，即使对于中等 n 也是完全不可行的。 

关键的观察是，我们可以推理最大元素的分布，而不是直接推理子集。 等于某个值 x 的最大值可以用所有选定元素位于 {1, ..., x} 内的事件减去全部位于 {1, ..., x-1} 内的事件来表示。 这将问题转换为计算约束子集，即简单的二项式系数表达式。 

从这里开始，期望的线性允许我们将最大值的期望重写为 P(max > i) 形式的概率之和。 每个这样的概率仅取决于子集是否避免了大于 i 的元素，这又变成了简单的组合比率。 这减少了从对子集求和到对前缀约束求和的问题，这可以使用已知的组合恒等式（特别是曲棍球棒恒等式）来简化。 

简化后，固定 k 的期望折叠成仅依赖于 n 和 k 的封闭形式，消除了对期望内迭代 i 的任何依赖。 

最后，我们对从 1 到 n 的所有 k 进行平均。 这引入了涉及 1/(k+1) 的项和，这正是一个类似调和数的结构。 预计算谐波数允许在 O(n) 预处理后在每 n 的恒定时间内回答所有测试用例。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集的暴力破解 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 组合+调和简化| O(N) 预处理，每个查询 O(1) | O(N) | 已接受 |

 ## 算法演练

 核心思想是停止明确地考虑子集，而是跟踪每个值成为最大值的频率。 

1. 我们固定子集大小 k 并表示所选子集的最大值至多为某个值 i 的概率。 当从前 i 个整数中选择所有 k 个元素时，就会发生这种情况，其概率为 C(i, k) / C(n, k)。 这种重新表述用纯粹的计数约束取代了关于最大值的推理。 
2. 我们将最大值的期望转换为尾和形式，将其写为 P(max > i) 的 i 上的和。 此步骤很有用，因为事件“max > i”是简单组合事件的补集，比直接对最大值求和更容易计算。 
3. 我们代入概率表达式并简化二项式系数的求和结果。 和的结构揭示了 C(i, k) 形式的重复项，这表明使用曲棍球棒恒等式来折叠累积二项式和。 
4. 应用组合恒等式后，固定 k 的期望简化为仅涉及 n、k 和单个二项式项的紧凑表达式。 结果不再需要迭代 i 或子集。 
5. 然后我们对从 1 到 n 的所有 k 进行平均 E[X_k]。 这引入了 k+1 的倒数之和，自然地形成了调和数。 我们将总和重写为 H_{n+1} 减 1。 
6. 我们使用简单的递归来预先计算高达 n 的谐波数，以便可以在恒定时间内回答每个查询。 

它之所以有效，是因为每个转换都通过在同一事件空间的计数解释之间切换来保持等效性。 概率空间在 k 个子集上是均匀的，因此每个事件都简化为组合的比率。 每个代数简化都有效地聚合了子集的对称贡献，并且出现了调和结构，因为每个元素的贡献仅取决于其下方的元素数量，而不取决于确切的子集配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ns = [int(input()) for _ in range(t)]
    max_n = max(ns)

    # precompute harmonic numbers H[i] = 1 + 1/2 + ... + 1/i
    H = [0.0] * (max_n + 2)
    for i in range(1, max_n + 2):
        H[i] = H[i - 1] + 1.0 / i

    # final formula: E = n + 1 - (n + 1) * (H[n + 1] - 1) / n
    # derived from averaging E[X_k]
    out = []
    for n in ns:
        if n == 1:
            out.append("1.0")
            continue
        val = (n + 1) - (n + 1) * (H[n + 1] - 1) / n
        out.append(str(val))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案首先读取所有测试用例，以便可以预先计算谐波数，直至达到最大 n。 这避免了每个测试用例的重新计算。 

调和数组 H 存储倒数的前缀和，这是必不可少的，因为最终表达式取决于 1/(k+1) 类型项的和。 使用浮点算术就足够了，因为预期值不需要是精确的整数值。 

处理 n = 1 的特殊情况，其中公式涉及除以 n 和调和项，否则会引入不必要的浮点边缘行为。 

## 工作示例

 考虑 n = 2。 

我们预先计算 H：H1 = 1，H2 = 1.5，H3 = 1.8333...

 我们计算：

 | n | H[n+1] | H[n+1] H[n+1] - 1 | H[n+1] - 1 (n+1)*(H[n+1]-1)/n | 最终值|
 | --- | --- | --- | --- | --- |
 | 2 | 1.8333 | 0.8333 | (3 * 0.8333)/2 = 1.25 | 3 - 1.25 = 1.75 | 3 - 1.25 = 1.75

 这显示了调和项如何直接减少线性基线 n+1。 

现在考虑 n = 1。 

| n | H2 | 公式行为 | 输出|
 | --- | --- | --- | --- |
 | 1 | 1.5 | 1.5 使用特殊情况| 1.0 |

 这证实了边缘情况避免了除法并且仍然返回正确的确定性最大值。

 ## 边缘情况

 对于 n = 1，该公式通常涉及除以 n 并评估谐波差，这可能会产生不稳定的浮点运算。 在这种情况下，算法显式返回 1.0，因为唯一的子集始终具有最大值 1，因此期望是确定性的。 

对于非常大的 n，谐波数 H[n] 是增量计算的，因此通过从 1 向上构建而不是独立地对每个查询的倒数求和来最小化精度损失。 这确保了浮点贡献的一致累积。 

对于 n = 2，表达式在很大程度上取决于 H[3]，1/2 和 1/3 中的小舍入差异可能会稍微改变最终值。 直接前缀结构确保两者都包含一次，从而保持最终期望的稳定性。
