 ## 解决方案
 ## 问题理解

 我们正在处理一个图，其中每个状态都是有向边遍历决策，而不仅仅是顶点值。 对于每个顶点$v$，以及每一个邻居$u$与它相邻，我们定义一个数量$L(v, u)$这代表从 开始的最长可能步行$v$并被迫占据优势$(v, u)$作为它的第一步。 第一步之后，步行将继续从$u$，但不允许立即返回$v$以在递归中创建微不足道的回溯依赖的方式。 

关键思想是计算$L(v, u)$取决于表格的值$L(u, w)$为所有邻居$w \neq v$。 因此，每个有向边缘状态都取决于其下一个顶点的所有其他传出边缘状态，除了指向其来源位置的边缘状态。 

这会在有向边而不是顶点上创建依赖结构。 输出最终来自于这些$L(v, u)$值，通常会汇总为所有起始选择的最佳答案。 

输入描述了一个无向图$n$顶点和$m$边缘。 目标是在上述依赖规则下计算一组全局一致的最长路径值。 

从复杂性的角度来看，两者$n$和$m$是线性尺度约束。 这立即排除了边缘中的任何二次方，因为$m$可以是$10^5$或者$2 \cdot 10^5$。 任何解决方案都必须有效地处理每个有向边恒定的次数。 由于每个无向边对应于两个有向状态，因此我们在大小为$O(n + m)$，这强烈建议使用图 DP 或依赖结构上的单遍传播。 

当图表包含循环时，就会出现一个微妙的问题。 一个朴素的递归定义$L(v, u)$看起来它可以无限期地重新访问相同的边缘状态，特别是在循环组件中。 挑战在于，尽管图是无向的，但一旦通过依赖方向正确定向，有向边缘状态之间的依赖关系就会形成有向非循环结构。 

当尝试在没有记忆顺序的情况下进行简单的 DFS 重新计算时，会出现典型的失败情况：

 输入：```
3 3
1 2
2 3
3 1
```在三角形中，计算$L(1,2)$取决于$L(2,3)$，这取决于$L(3,1)$，循环回到$L(1,2)$。 没有排序的简单递归要么无限循环，要么重复重新计算状态。 

正确的输出仍然是明确定义的，但前提是依赖关系以边缘状态上的有效拓扑顺序得到解决。 

## 方法

 直接的暴力方法会尝试计算每个$L(v, u)$独立使用递归。 从一个顶点$u$，我们尝试每个邻居$w \neq v$, 计算$L(u, w)$，并取最佳延伸。 这很快扩展到对图的每个有向边的全面探索。 

由于有$2m$有向边缘状态，并且每个状态都可以触发对节点的几乎所有邻居的遍历，最坏情况的复杂度变为$O(m \cdot n)$在稠密或循环图中。 这太慢了。 

关键的观察结果是依赖关系是本地构建的。 每个$L(v, u)$取决于所有传出状态$u$，除了一个。 这意味着如果我们已经知道所有值$L(u, w)$，然后计算$L(v, u)$只是聚合它们。 问题变成了值在有向边上的传播，其中每个节点都会等待，直到知道其依赖状态之一之外的所有状态。 

这建议为每个有向边维护一个计数器，记录有多少必需的依赖关系仍未解决。 我们可以将每个顶点视为管理一个“等待前辈”队列，该队列取决于其传出边缘状态。 一旦有一个值$L(u, w)$被计算后，它减少了相关状态的未决要求，并可能解锁新的计算。 这本质上是隐式定向非循环结构上的依赖性解析过程。 

该过程成为类似于拓扑排序的基于队列的传播，但应用于边缘状态而不是顶点。 每个状态只处理一次，并且每个依赖项更新都在恒定时间内处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(m \cdot n)$|$O(n)$| 太慢了|
 | 最佳 |$O(n + m)$|$O(n + m)$| 已接受 |

 ## 算法演练

 我们重新解释每个有向边缘状态$(v, u)$作为依赖系统中的节点。 对于每个这样的状态，我们维护它所依赖的“仍然缺失”的子状态的数量。 

1. 构建图的邻接表并处理每个有向边$(v, u)$作为一种状态，我们需要计算。 的依赖性$(v, u)$是所有州$(u, w)$为了$w \neq v$。 
2. 对于每个顶点$u$，我们跟踪有多少传出定向边缘状态仍未最终确定。 最初，每个有向状态$(v, u)$取决于所有邻居$u$除了$v$，所以它的依赖计数是$\deg(u) - 1$。 
3. 使用依赖计数为零的所有有向边缘状态初始化队列。 当顶点的度数为 1 时，就会发生这种情况，因为那时唯一的状态没有替代的邻居可供依赖。 这些是不可能进一步扩展的基本情况。 
4. 迭代处理队列。 当一个状态$(v, u)$解决后，我们将其影响传播到所有依赖它的国家。 这意味着我们减少了状态的依赖计数器$(u, x)$在哪里$x \neq v$。 这反映出需要继续$u$现已解决。 
5. 每当某个状态的依赖计数器降至零时$(u, x)$，这意味着所有必需的延续都已计算完毕，因此我们计算$L(u, x)$并将其推入队列。 
6. 继续，直到处理完所有可达的有向边缘状态。 

正确性依赖于这样一个事实：当每个状态所依赖的所有状态都已最终确定时，每个状态就变得可计算。 

### 为什么它有效

 该系统定义了由父顶点的依赖性排除引起的有向边缘状态的偏序。 尽管原始图可能包含循环，但状态之间的依赖关系是非循环的，因为每个转换都严格从一个状态开始$(v, u)$植根于的国家$u$但不包括$v$，防止立即逆转并确保没有依赖循环可以关闭。 这保证了基于队列的解析在隐式依赖图上以有效的拓扑顺序处理状态，因此每个$L(v, u)$只计算一次，所有必需的子问题都已解决。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque, defaultdict

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    edges = []
    for _ in range(m):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)
        edges.append((a, b))

    # Each directed edge (v -> u) is a state
    # We map states to ids
    state_id = {}
    rev_state = []
    
    for v in range(1, n + 1):
        for u in g[v]:
            state_id[(v, u)] = len(rev_state)
            rev_state.append((v, u))

    deg = [len(g[v]) for v in range(n + 1)]
    
    # dependency count: deg[u] - 1 for state (v -> u)
    indeg = [0] * len(rev_state)
    dependents = [[] for _ in range(len(rev_state))]

    pos = defaultdict(list)
    for idx, (v, u) in enumerate(rev_state):
        pos[u].append(idx)

    # Build dependency graph
    for idx, (v, u) in enumerate(rev_state):
        indeg[idx] = deg[u] - 1

    # For each state (v->u), all states (u->w), w != v depend on it
    for idx, (v, u) in enumerate(rev_state):
        for w in g[u]:
            if w == v:
                continue
            to_idx = state_id[(u, w)]
            dependents[idx].append(to_idx)

    q = deque()
    for i in range(len(rev_state)):
        if indeg[i] == 0:
            q.append(i)

    value = [0] * len(rev_state)

    while q:
        cur = q.popleft()
        v, u = rev_state[cur]

        for nxt in dependents[cur]:
            value[nxt] = max(value[nxt], value[cur] + 1)
            indeg[nxt] -= 1
            if indeg[nxt] == 0:
                q.append(nxt)

    # final answer is max over all states
    print(max(value) if value else 0)

if __name__ == "__main__":
    solve()
```该代码将每个有向边显式建模为 DP 状态。 邻接结构`dependents`对给定状态解决后哪些状态可用进行编码。 这`indeg`数组跟踪每个状态在计算之前还有多少剩余依赖关系。 

队列首先处理所有基本状态，这些状态是在依赖意义上附加到叶子的状态。 每次解决一个状态时，它都会通过增加相关状态的最佳已知值来扩展相关状态中的路径。 

一个微妙的点是，一旦某个状态的依赖计数达到零，我们就永远不会重新访问该状态。 这确保了线性复杂性，因为每个状态被推送一次并且每个依赖边被处理一次。

 ### 示例 1

 输入：```
3 2
1 2
2 3
```国家：

 (1,2), (2,1), (2,3), (3,2)

 我们追踪`(value, indeg)`。 

| 步骤| 加工状态| 价值| 效果|
 | --- | --- | --- | --- |
 | 1 | (1,2), (3,2) | (1,2), (3,2) | 0 | 两者都是基节点（1 度节点）|
 | 2 | (2,1) | 1 | 扩展到 (2,3) |
 | 3 | (2,3) | 1 | 最终传播|

 最终答案是1。 

这显示了线性链传播，其中依赖性从叶子向内流动。 

### 示例 2

 输入：```
4 4
1 2
2 3
3 4
4 2
```这创建了一个带有尾部结构的循环。 

| 步骤| 加工状态| 价值| 效果|
 | --- | --- | --- | --- |
 | 1 | (1,2) | 0 | 基地|
 | 2 | (3,4) | 0 | 由于结构的原因，是基础的|
 | 3 | (2,3) | 1 | 从 3 | 扩展

 由于依赖性排除可以防止循环等待，因此循环得以解决。 

这演示了循环图如何在依赖状态空间中变成非循环的。

 ## 边缘情况

 单边图是最干净的基本情况。 用于输入`1-2`，两个有向状态都没有替代的延续，因此两者都可以立即计算。 队列以两种状态开始，并且不会发生传播。 

三角图测试循环依赖性。 尽管每个状态都依赖于另一个状态，但排除反向边缘会打破依赖空间中的循环，从而允许从具有最小入度的任何状态进行初始化，并一致地传播，直到所有状态稳定为止。 

星形图测试高度不平衡。 中心节点有很多依赖关系，但所有叶子状态都是独立的基本情况，因此计算正确地向内流动，不会出现死锁。
