 ## 解决方案
 ## 问题理解

 给定一个在正整数对上定义的过程$(a, b)$和$a < b$。 来自一个州$(a, b)$，系统要么立即终止，概率为$1/2$，或转换到新状态$(2a, b - a)$有概率$1/2$。 这定义了一个随机过程，其中每个步骤要么结束该过程，要么确定性地转换该对。 

有单吸特殊配置$(S/2, S/2)$， 在哪里$S = a + b$。 从这一状态开始，无论随机性如何，该过程都会以一步完成，因此其预期步骤数为 1。 

任务是计算预期的步数$E_{a,b}$从给定的对开始。 

尽管递归看起来像概率马尔可夫过程，但其结构受到高度约束：每个转换都保留总和$S$，并且状态空间以非常严格的算术方式演化。 这使得问题无需线性代数或所有对上的完整 DP 即可解决。 

约束（从编辑上下文中隐含）允许较大的值$a, b$，因此任何明确探索没有结构的状态的解决方案都会失败。 对可达状态的幼稚期望 DP 很容易降级为指数探索，因为每个状态都可能生成一系列进一步的状态。 

当特殊状态时会出现微妙的边缘情况$(S/2, S/2)$无法到达。 在这种情况下，递归不会按照通常的意义终止，并且期望稳定到恒定值。 例如，如果我们永远无法达到相等的一半，则重复替换会不断循环相同结构的缩放版本，并且预期值会崩溃到一个固定点。 

另一个重要的极端情况是进程通过少量步骤达到特殊状态。 在这种情况下，期望非常接近 2，但稍小，具体取决于到终止的距离。 

## 方法

 直接的方法就是治疗$E_{a,b}$作为一个方程组。 每对$(a,b)$给出一个方程$$E_{a,b} = 1 + \frac{1}{2} E_{2a, b-a}$$以及特殊的状态$(S/2, S/2)$具有价值 1。人们可以尝试通过递归评估状态并记忆结果来解决这个问题。 这在概念上是有效的，因为递归只会向前移动到另一对。 

然而，过渡$(a,b) \to (2a, b-a)$不会以直接的方式产生小的或有界的状态空间。 值以混合方式增长和收缩，并且天真的记忆在识别循环或终止之前仍然探索潜在的长链。 在病理情况下，递归可以模拟总和上的长二进制过程$S$，导致深度与$S$，太大了。 

关键的结构见解是总和$S = a + b$是不变的，唯一有意义的目标状态是$(S/2, S/2)$。 转换的行为类似于比率的二元运算$a/b$，系统的演化方式对应于在乘法和减法规则下重复变换分子和分母。 这创建了一个隐藏的二进制结构：每一步都有效地在两半之间转移信息$S$。 

由此可以证明，如果目标状态是可达的，则可以通过以下步骤达到目标状态：$O(\log S)$。 否则，该过程会陷入确定性循环，其中所有状态都满足相同的期望值。 

这将问题简化为最多模拟对数步，同时跟踪系统是否达到对称状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力递归+备忘录|$O(\text{states visited})$，最差$O(S)$|$O(S)$| 太慢了|
 | 最优算术模拟|$O(\log S)$|$O(1)$| 已接受 |

 ## 算法演练

 核心思想是模拟变换，同时检查我们是否达到对称状态。 

1.从对开始$(a, b)$并计算$S = a + b$。 目标配置是$(S/2, S/2)$，它只能存在，如果$S$是均匀的。 如果$S$为奇数，立即不可达，所以答案必须是固定值2。 
2.如果$S$是均匀的，重复应用过渡$(a, b) \to (2a, b - a)$。 每一步都保留$S$，所以我们只跟踪该对在此线性变换下如何演化。 
3. 每次转换后，检查当前对是否等于$(S/2, S/2)$。 如果是，记录步数$k$需要到达它并停止模拟。 然后，预期值仅由该距离确定。 
4. 最多继续模拟$O(\log S)$步骤。 这个界限来自这样一个事实，即该对通过乘法和减法缩放演化，这迫使系数的二元结构快速增长。 
5. 如果在有限步数内从未达到对称状态，则得出无法达到的结论并返回 2。 
6. 如果达到$k$步骤，使用封闭形式计算期望$2 - 2^{-k}$。 

其工作原理：该过程定义了一个状态图，其中只有一个吸收节点$(S/2, S/2)$。 每个状态要么位于到该节点的路径上，要么是与其不相交的循环的一部分。 如果路径存在，重复的变换将问题简化为深度度量$k$，因为每一步都会使剩余不确定性几何减半。 如果不存在路径，则所有可达状态都位于闭合组件中，在该闭合组件中递归折叠到固定点 2。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())
    S = a + b

    if S % 2:
        print(2)
        return

    target = S // 2
    seen_steps = 0

    # limit is logarithmic in S
    for _ in range(60):
        if a == target and b == target:
            print(2 - 2 ** (-seen_steps))
            return
        a, b = 2 * a, b - a
        seen_steps += 1

    print(2)

if __name__ == "__main__":
    solve()
```该实现完全按照流程中的定义反映了转换。 总和$S$计算一次并仅用于定义目标状态。 奇偶校验至关重要，因为它会立即排除任何达到相等一半的可能性$S$很奇怪。 

循环界限 60 是典型约束的安全对数上限，因为值在结构上而不是在幅度上呈指数增长和收缩。 每次迭代都严格按照递归指定的方式更新该对，并且步计数器跟踪我们距离终止有多远。 

表达式$2 - 2^{-k}$仅当达到目标时才计算，这对应于编辑逻辑中的引理2。 

## 工作示例

 ### 示例 1

 输入：```
1 3
```这里$S = 4$，所以目标是$(2,2)$。 

| 步骤| 一个 | 乙| 状态| 达到目标 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 3 | (1,3) | 没有|
 | 1 | 2 | 2 | (2,2) | 是的 |

 我们一步就达到了目标，所以答案是$2 - 2^{-1} = 1.5$。 

该轨迹显示了最简单的可达到的情况：系统在一次转换后立即达到平衡。 

### 示例 2

 输入：```
1 2
```这里$S = 3$，这很奇怪。 

由于平等分裂是不可能的，因此该过程永远不会达到对称状态。 

输出是：```
2
```这说明了仅奇偶性决定答案的无法到达的情况。

 ## 边缘情况

 当$S$为奇数时，算法立即返回 2，无需模拟。 例如，输入$(1,2)$产生$S=3$，因此进一步的转换并不重要，因为相等的分裂在算术上是不可能的。 如果尝试继续，模拟循环将是不必要的，并且可能会产生误导。 

当初始状态已经对称时，例如$(4,4)$，算法在步骤 0 正确识别目标。预期值为 1，因为进程在特殊状态下立即终止。 

当系统仅经过一次转换就达到目标时，例如$(1,3)$，循环立即捕获转换并返回$2 - 2^{-1}$。 正确性取决于应用最终相等性检查之前的计数步骤，这确保指数反映实际的递归深度。
