 ## 解决方案
 ## 问题理解

 我们有一行`n`树，每棵树都有一定的高度，我们的任务是调整它们的一些高度，使行形成一个“美丽”的序列。 如果一个序列围绕其中心对称，并且距离两端每一步正好增加 1，那么该序列就是美丽的。 具体来说，第一棵树和最后一棵树必须具有相同的高度，第二棵树和倒数第二棵树必须具有相同的高度，并且比第一棵树高，依此类推。 我们可以将树的高度更改为任何正整数，但每次更改的成本都很高，因此我们希望尽量减少更改的次数。 输出是需要调整的最小树数。 

输入大小可以大到100,000棵树，每个高度也可以高达100,000。 在 2 秒的时间限制下，算法的二次方`n`会太慢。 我们需要一个线性或接近线性扩展的解决方案`n`。 

一个不明显的边缘情况发生在已经几乎很漂亮但中间稍有偏差的序列中。 例如，`[2, 2, 2]`应该产生最小的变化 1，因为只有中间的树需要调整。 另一个棘手的情况是`[1, 3, 3, 1]`。 一种仅检查对称性而不考虑增量差异的幼稚方法会错误地得出它已经很漂亮的结论。 我们必须考虑对称性和精确的增量模式。 

## 方法

 蛮力方法会尝试第一棵树的所有可能的起始高度，并尝试从中构建一个漂亮的序列。 对于每个候选起始高度，我们将计算需要进行多少次更改并选择最小值。 这种做法是正确的，但效率低下。 如果我们让第一棵树在所有可能的高度上变化，最多 100,000，并且对于每个高度，我们扫描所有`n`树，最坏情况的操作数是`n * max(a_i)`这对于`n = 10^5`。 

关键的观察是每棵树与其对称对应树之间的差异是可以预测的。 如果我们定义高度`i`美丽序列中的第棵树为`h + i - 1`（对于前半部分）并镜像后半部分，当我们调整增量距离时，问题减少到找到最常见的有效起始高度。 形式上，如果我们从前半部分的每个高度中减去距第一端的距离，并在后半部分中减去距最后一端的镜像距离，则所得数字在完美序列中应该都是相同的。 计算这些“调整高度”中最常见的数字可以告诉我们哪个起始高度可以最大限度地减少变化。 那么变化的次数就是`n`减去最常见调整值的频率。 

这将问题转化为带有频率计数器的线性扫描，该频率计数器运行在`O(n)`时间和`O(n)`空间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n * 最大(a_i)) | O(1) | O(1) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算每棵树的“距离调整高度”。 对于树`i`（0-indexed）在前半部分，减去它的索引`i`从`a[i]`。 对于树`i`后半部分减去`(n - 1 - i)`从`a[i]`。 这为我们提供了有效的起始高度，如果该树是理想序列的一部分，那么该高度将使序列变得美丽。 
2. 使用字典或哈希图统计每个调整高度的频率。 每个唯一的调整高度代表一个候选起始高度，其频率表示有多少棵树已经与该候选对齐。 
3. 找出最大频率。 该频率对应于需要最少变化的候选起始高度。 
4. 最少的改变次数是`n`减去这个最大频率，因为所有不匹配最频繁调整高度的树都必须被修改。 

工作原理：通过根据距最近边缘的距离调整高度，我们将所有树标准化为“公共基线”，该基线代表美丽序列的起始高度。 最大化已经与该基线对齐的树的数量可以直接最小化更改的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import defaultdict

n = int(input())
a = list(map(int, input().split()))

counter = defaultdict(int)

for i in range(n):
    if i <= (n - 1 - i):
        key = a[i] - i
    else:
        key = a[i] - (n - 1 - i)
    counter[key] += 1

max_freq = max(counter.values())
print(n - max_freq)
```我们使用快速 I/O 来处理大输入。 距离调整以漂亮的顺序将每棵树的高度标准化为其有效起始高度。 使用字典可以确保我们可以有效地计算频率。 最后，减去最大频率`n`给出最少的更改数量。 微妙之处包括根据数组的边正确识别要减去的距离，并确保索引被处理为从 0 开始。
