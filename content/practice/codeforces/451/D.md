 ## 解决方案
 ## 问题理解

 我们得到一个仅包含以下内容的二进制字符串`'a'`和`'b'`。 对于每个子字符串，我们重复地将连续的相等字符合并为单个字符。 例如：

-`"aaaa"`变成`"a"`-`"aabbaa"`变成`"aba"`-`"abbba"`变成`"aba"`如果这些合并后获得的压缩字符串是回文，则该子字符串被称为好的子字符串。 

任务不是列出子字符串。 我们只需要统计有多少个偶数长度的好子串和有多少个奇数长度的子串。 

字符串长度可以达到$10^5$。 子串计数已经$O(n^2)$，因此单独检查每个子字符串是不可能的。 即使对每个子串进行线性扫描也会导致粗略的结果$10^{10}$最坏情况下的操作，远远超出了2秒的时间限制。 该解决方案必须利用一些隐藏结构并接近线性时间运行。 

问题最微妙的部分是了解压缩操作实际发生的变化。 

考虑子串`"abba"`。 

压缩后：$$"abba" \rightarrow "aba"$$这是一个回文，所以子串很好。 

现在考虑`"abab"`。 

压缩不会改变任何内容：$$"abab" \rightarrow "abab"$$这不是回文。 

一个常见的错误是认为必须为每个子字符串计算整个压缩字符串。 关键的观察结果是，对于二进制字母表，回文条件变得简单得多。 

另一个容易出现的陷阱是由一个重复字符组成的子字符串。 例如：```
aaaa
```每个子串压缩为`"a"`，这是一个回文。 任何仅基于压缩字符串形状的解决方案仍然必须正确计算所有长度。 

最后的边缘情况是交替字符串，例如：```
ababab
```压缩不会执行任何操作，因此效果完全取决于原始子字符串。 这种情况暴露了关于相同字符运行的错误假设。 

## 方法

 强力解决方案将枚举每个子字符串，压缩它，并测试压缩结果是否是回文。 

有$O(n^2)$子串。 单次压缩可能需要$O(n)$时间、给予$O(n^3)$总的复杂性。 即使进行了一些优化，独立检查每个子字符串至少仍然保持不变$O(n^2)$，这对于$n=10^5$。 

突破来自于理解二进制字母表中一个好的子串是什么样子。 

取任意子串。 压缩连续的相等字符后，结果是交替序列，因为相邻的相等字符已被合并掉。 

由于仅`'a'`和`'b'`存在，每个压缩字符串必须类似于以下之一：$$a,\quad b,\quad ab,\quad ba,\quad aba,\quad bab,\quad abab,\ldots$$当交替二进制字符串的长度为奇数时，它就是回文串。 

例如：$$aba,\ bab,\ ababa$$是回文，而$$ab,\ ba,\ abab$$不是。 

现在看一个子串$s[l..r]$。 

它的压缩形式开始于$s[l]$并以$s[r]$。 

由于压缩字符串是交替的，因此当且仅当其第一个和最后一个字符相等时它才是回文。 

这意味着：

 当且仅当子字符串的第一个和最后一个字符相等时，子字符串才是好的。 

这完全消除了压缩的需要。 

问题变成了对端点包含相同字符的子字符串进行计数，并将其分为偶数和奇数长度。 

假设我们从左到右处理位置。 

对于固定的结束位置$i$，每个好的子串都以$i$必须从较早的位置开始$j$和：$$s[j] = s[i]$$子串长度的奇偶校验为：$$(i-j+1)$$当出现奇数长度时$i$和$j$具有相同的索引奇偶性。 

当出现偶数长度时$i$和$j$具有相反的奇偶性。 

所以我们只需要知道，对于每个角色（`a`或者`b`），有多少个先前出现的出现在偶数位置，有多少出现在奇数位置。 

这给出了一个$O(n)$解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$|$O(n)$| 太慢了|
 | 最佳 |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1.维护四个柜台。`a_even`,`a_odd`,`b_even`， 和`b_odd`存储有多少个处理位置包含每个字符和每个索引奇偶校验。 
2. 从左到右扫描字符串。 

使用从零开始的索引。 
3. 对于当前位置$i$，判断是否$i$是偶数还是奇数。 
4. 计算以奇数长度结尾的好子串$i$。 

起始位置必须包含相同的字符并且具有相同的奇偶校验$i$。 

如果当前字符是`'a'`和$i$是偶数，加`a_even`。 

如果当前字符是`'a'`和$i$是奇数，加`a_odd`。 

同样的想法适用于`'b'`。 
5. 计算以 结尾的偶数长度的好子串$i$。 

起始位置必须包含相同的字符并且具有相反的奇偶性。 

如果当前字符是`'a'`和$i$是偶数，加`a_odd`。 

如果当前字符是`'a'`和$i$是奇数，加`a_even`。 

同样的想法适用于`'b'`。 
6. 统计单字符子串。 

每个长度为一的子串都是好的并且具有奇数长度，因此在奇数答案上加一。 
7. 将当前位置插入相应的计数器中。 

未来的子串可能从这里开始。 
8. 继续，直到处理完整个字符串。 

### 为什么它有效

 压缩的二进制字符串总是在`'a'`和`'b'`。 当这样的字符串的第一个和最后一个字符相等时，它就是回文字符串。 压缩字符串的第一个和最后一个字符恰好是原始子字符串的第一个和最后一个字符。 因此，当子串的端点相等时，它就是好的。 

将问题简化为端点相等后，仅通过奇偶校验来确定子串长度是奇数还是偶数。 具有相同奇偶校验的两个索引会生成奇数长度的子字符串，而奇偶校验相反的两个索引会生成偶数长度的子字符串。 维护的计数器精确计数那些可以作为有效起点的较早位置，因此每个好的子串在处理其右端点时都会被计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()

even_good = 0
odd_good = 0

a_even = a_odd = 0
b_even = b_odd = 0

for i, ch in enumerate(s):
    if ch == 'a':
        if i % 2 == 0:
            odd_good += a_even
            even_good += a_odd
            a_even += 1
        else:
            odd_good += a_odd
            even_good += a_even
            a_odd += 1
    else:
        if i % 2 == 0:
            odd_good += b_even
            even_good += b_odd
            b_even += 1
        else:
            odd_good += b_odd
            even_good += b_even
            b_odd += 1

    odd_good += 1

print(even_good, odd_good)
```该算法只对每个位置处理一次。 

四个计数器代表按索引奇偶校验分割的每个字符的所有先前出现的次数。 当位置`i`到达时，每个好的子串都以`i`必须从先前出现的相同字符开始。 

如果起始位置和结束位置具有相同的奇偶校验，则子串长度为奇数。 如果奇偶校验不同，则子串长度为偶数。 这让我们可以在恒定的时间内更新两个答案。 

位置处的单字符子串`i`总是好的，所以`odd_good`每个字符递增一次。 

操作顺序很重要。 在将当前仓位插入计数器之前，必须添加之前仓位的贡献。 否则，当前位置将错误地与其自身形成长度为零的子字符串。 

Python 整数自动处理大约最大的值$n^2$，这是必要的，因为答案可以达到$5 \times 10^9$。

 ## 边缘情况

 考虑输入：```
aaaa
```每个子串压缩为`"a"`，所以每个子串都是好的。 该算法纯粹通过端点相等来计算子字符串。 由于每个端点对都包含`'a'`，每个子串都被计算在内。 结果是：```
4 6
```它匹配长度为四的字符串的总共十个子字符串。 

现在考虑：```
abab
```压缩不会改变任何事情。 好的子字符串正是那些第一个和最后一个字符匹配的子字符串。 唯一的这样的子串是四个单个字母和两个长度为三的子串。 算法达到：```
0 6
```因为没有偶数长度的子串具有匹配的端点。 

最后考虑：```
abba
```整个字符串压缩为`"aba"`，这是一个回文。 仅对原始字符串进行推理的幼稚实现可能会错过这一点。 端点特征立即处理它：第一个和最后一个字符都是`'a'`，所以子串是好的。 算法通过匹配来计数`'a'`出现在位置$0$和$3$，添加一个偶数长度的好子串。
