 ## 解决方案
 ## 问题理解

 我们得到一个不同整数的数组。 任务是确定在恰好反转一个连续段后整个数组是否可以按升序排序。 

如果可能的话，我们必须打印`"yes"`和一个有效段`[l, r]`其反转对数组进行排序。 如果不可能，我们打印`"no"`。 

数组大小可以大到$10^5$。 在这种规模下，重复复制或排序大部分数组的算法变得昂贵。 具有二次行为的解决方案，例如尝试每个可能的段并检查结果，将需要大约$10^{10}$在最坏的情况下进行操作，远远超出了时间限制。 线性或$O(n \log n)$解决方案很容易足够快。 

一些边缘情况值得关注。 

考虑一个已经排序的数组：```
5
1 2 3 4 5
```正确答案是：```
yes
1 1
```反转长度为 1 的段没有任何改变，因此仍然满足要求。 粗心的实现可能会错误地打印`"no"`因为不存在减少的部分。 

考虑一个完全反转的数组：```
3
3 2 1
```正确答案是：```
yes
1 3
```整个数组形成一个递减段，将其反转即可对数组进行排序。 

考虑多个单独的反转：```
5
3 1 2 5 4
```正确答案是：```
no
```没有单一的连续逆转可以修复两个无序位置。 仅查看第一个反转的实现可能会错误地接受这种情况。 

考虑接触端点的递减线段：```
5
1 5 4 3 6
```正确答案是：```
yes
2 4
```必须仔细处理反转段周围的边界检查，因为一侧可能不存在。 

## 方法

 一个简单的暴力解决方案会尝试每一个可能的部分$[l,r]$。 对于每个选择，反转该段，检查结果数组是否已排序，如果找到有效段则停止。 

这种方法是正确的，因为它明确地检查每个允许的操作。 问题是运行时间。 有$O(n^2)$可能的片段。 检查结果数组是否已排序的成本$O(n)$。 总复杂度变为$O(n^3)$，这对于$n=10^5$。 

关键的观察是，如果单个反转可以对数组进行排序，那么所有无序必须集中在一个连续的递减块中。 

查看此情况的一个有用方法是将数组与其排序版本进行比较。 由于所有值都是不同的，因此每个元素都有唯一的正确位置。 如果反转一段就固定了数组，那么原数组与排序后数组不同的位置必然形成一个连续的区间。 

我们可以构造数组的排序版本，而不是测试所有反转。 然后我们找到数组不同的第一个位置和它们不同的最后一个位置。 这些职位定义了唯一值得逆转的候选细分市场。 

如果反转该段会产生排序数组，则答案是`"yes"`。 否则，不存在有效段。 

这将问题简化为一种排序和一种验证。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$|$O(n)$| 太慢了|
 | 最佳 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 读取数组并创建它的排序副本。 
2. 查找原数组与已排序数组不同的所有位置。 
3. 如果没有不同的位置，则数组已排序。 输出`"yes"`和该段`1 1`。 
4. 否则，让`l`是第一个不同的位置并且`r`是最后一个不同的位置。 
5. 反转该段`l`到`r`在原始数组的副本中。 
6. 将修改后的数组与排序后的数组进行比较。 
7. 如果相同，则输出`"yes"`和指数`l+1`和`r+1`因为该问题使用从 1 开始的索引。 
8.否则，输出`"no"`。 

### 为什么它有效

 让$b$是数组的排序版本。 

假设一些反转对数组进行排序。 在反向段之外，元素永远不会移动，因此这些位置必须已经匹配$b$。 因此，原始数组和原始数组之间的每个不匹配$b$必须位于一个连续的区间内。 

第一个不匹配和最后一个不匹配唯一确定包含所有不匹配的最小间隔。 任何有效的反转都必须恰好覆盖该区间。 反转任何较小的间隔会至少保留一个不匹配，而反转任何较大的间隔会更改已匹配的位置。 

该算法反转这个唯一可能的候选区间，并直接检查结果是否等于排序后的数组。 如果是这样，则存在有效的反转。 如果没有，则任何一次反转都无法对数组进行排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    b = sorted(a)

    diff = [i for i in range(n) if a[i] != b[i]]

    if not diff:
        print("yes")
        print(1, 1)
        return

    l = diff[0]
    r = diff[-1]

    c = a[:]
    c[l:r + 1] = reversed(c[l:r + 1])

    if c == b:
        print("yes")
        print(l + 1, r + 1)
    else:
        print("no")

solve()
```该解决方案首先创建完全排序的目标数组。 由于任何成功的结果都必须等于此排序版本，因此它可以作为整个算法的参考。 

名单`diff`存储当前数组与已排序数组不一致的每个位置。 如果此列表为空，则数组已排序。 允许反转长度为 1 的段，因此答案立即`"yes"`带索引`1 1`。 

当存在不匹配时，第一个和最后一个不匹配定义唯一的候选片段。 反转该范围会移动所有可能放错位置的元素，同时保持已经正确的位置不变。 

最终对比`c == b`充当完整的正确性检查。 这避免了关于边界和邻近值的棘手案例分析。 如果反转的数组与排序的数组完全匹配，则该段有效。 否则，不存在有效段。 

最常见的实现错误是忘记该问题使用基于 1 的索引。 在内部，我们使用 Python 的基于 0 的索引，并且仅在打印答案时进行转换。

# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    def solve():
        n = int(input())
        a = list(map(int, input().split()))

        b = sorted(a)

        diff = [i for i in range(n) if a[i] != b[i]]

        out = []

        if not diff:
            out.append("yes")
            out.append("1 1")
            return "\n".join(out)

        l = diff[0]
        r = diff[-1]

        c = a[:]
        c[l:r + 1] = reversed(c[l:r + 1])

        if c == b:
            out.append("yes")
            out.append(f"{l + 1} {r + 1}")
        else:
            out.append("no")

        return "\n".join(out)

    global input
    input = sys.stdin.readline
    return solve()

# already sorted
assert run("5\n1 2 3 4 5\n") == "yes\n1 1", "already sorted"

assert run("5\n1 5 4 3 6\n") == "yes\n2 4", "middle decreasing block"

 ## 边缘情况

 考虑一个已经排序的数组：```
5
1 2 3 4 5
```排序后的副本与原始数组相同。 不匹配列表为空，因此算法立即输出：```
yes
1 1
```长度为一的反转使数组保持不变，满足要求。 

考虑一个完全反转的数组：```
3
3 2 1
```不匹配位置是第一个和最后一个索引。 该算法选择整个数组作为候选段。 反转它会产生排序数组，产生：```
yes
1 3
```考虑多个单独的反转：```
5
3 1 2 5 4
```排序后的数组为：```
1 2 3 4 5
```第一个不匹配发生在索引 0 处，最后一个不匹配发生在索引 4 处。反转整个间隔可得出：```
4 5 2 1 3
```这是没有排序的。 最终比较失败，因此算法正确打印：```
no
```考虑接触端点的递减线段：```
5
5 4 3 2 6
```不匹配占据前缀。 该算法选择索引`0`通过`3`，反转该段，并获得：```
2 3 4 5 6
```它与排序后的数组匹配。 输出是：```
yes
1 4
```不需要特殊处理，因为最终的相等性检查会自动验证边界情况。
