 ## 解决方案
 ## 问题理解

 我们得到一个完美的二叉树，其顶点按堆顺序编号。 顶点`1`是根，并且对于每个顶点`i > 1`，它的父级是`i // 2`。 

一个排列`p`所有顶点的保留。 每次查询后，排列中的两个位置都会交换。 交换对于未来的查询仍然有效。 

每次交换之后，我们必须确定当前的排列是否可以通过树的深度优先遍历来产生。 DFS 是先序的：顶点在第一次访问时被写入。 唯一的自由是每个节点访问其子节点的顺序。 

树结构是固定的，非常特殊。 由于它是完美二叉树，因此每个内部节点恰好有两个子节点，并且所有叶子都位于同一层。 

最大的树包含`65535`顶点和所有测试用例的查询总数是`50000`。 每次交换后从头开始重新计算有效性的解决方案需要重复检查所有顶点。 在最坏的情况下，这大约变成$$65535 \times 50000 \approx 3.2 \cdot 10^9$$的操作，这是完全不可行的。 

完美二叉树中的 DFS 订单结构比一般树中的严格得多。 利用这种刚性是整个挑战。 

一个微妙的点是 DFS 订单不是唯一的。 例如，在树中```
    1
   / \
  2   3
```两个都```
1 2 3
```和```
1 3 2
```有效，因为 DFS 可以先选择其中一个孩子。 

另一个容易犯的错误是只检查父子关系。 

考虑```
1 2 4 3 5 6 7
```在有七个顶点的树中。 

每个父代都出现在其后代之前，但这不是 DFS 顺序。 一旦DFS进入子树`2`，它必须在移动到子树之前完成整个子树`3`。 顶点`3`出现得太早了。 

第三个陷阱是忘记子树的连续性。 

对于同一棵树，```
1 2 4 5 3 6 7
```有效，因为子树`2`占据一个连续的段。 

但```
1 2 4 3 5 6 7
```分裂子树`2`分成两部分，这是 DFS 永远无法做到的。 

这些观察结果直接导致正确的表征。 

## 方法

 最直接的解决办法就是模拟定义。 

每次交换后，重建排列中每个顶点的位置，并递归验证排列是否是有效的 DFS 顺序。 对于一个节点`v`，我们会检查`v`首先出现在其子树顶点中，并且每个子子树的顶点形成紧随其后出现的连续块。 

这是正确的，因为它与前序 DFS 的递归结构完全匹配。 

问题是成本。 验证整个排列需要检查所有`n`顶点。 在每次查询后执行此操作会产生结果`O(nq)`，太大了。 

关键的观察来自于 DFS 在树上的形状。 

在任何先序 DFS 顺序中，每个子树的顶点都占据一个连续的段。 由于我们的树是完美的，因此每个子树的大小都是预先知道的。 

让`sz[v]`是以子树为根的大小`v`。 

假设顶点`v`出现在位置`pos[v]`在排列中。 

然后是段```
[pos[v], pos[v] + sz[v] - 1]
```必须完全包含子树的顶点`v`。 

对于叶子来说，这是自动的。 

对于有子节点的内部节点`l`和`r`，预购DFS只有两种可能：```
v, subtree(l), subtree(r)
```或者```
v, subtree(r), subtree(l)
```由于两个子子树的大小都已知，因此我们可以在本地验证这两种排列之一是否发生。 

这会将全局 DFS 条件转换为局部条件的集合，每个顶点一个。 

交换后，只有位置发生变化的顶点及其祖先的顶点的有效性才会受到影响。 其他所有子树都看到与以前完全相同的排列。 

因为树的高度最多为$$\log_2 65535 = 16,$$交换仅影响`O(log n)`顶点。 

我们维护无效顶点的计数。 每次交换后，我们更新受影响的顶点并检查计数是否为零。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每个查询 O(n) | O(n) | 太慢了 |
 | 最佳 | 每次查询 O(log² n) | O(n) | 已接受 |

 ## 方法

 让我们将当地的情况正式化。 

对于每个顶点`v`, 定义一个布尔值`good[v]`。 

如果`v`是一片叶子，`good[v] = True`。 

否则就让它的孩子`l`和`r`。 

有效的预购 DFS 植根于`v`一定看起来像```
v
(child subtree A)
(child subtree B)
```在哪里`A`和`B`是`l`和`r`以任一顺序。 

让```
pv = pos[v]
pl = pos[l]
pr = pos[r]
```第一个子子树必须立即开始`v`。 

所以要么```
pl = pv + 1
and
pr = pv + 1 + sz[l]
```或者```
pr = pv + 1
and
pl = pv + 1 + sz[r]
```此外，两个孩子本身必须已经满足 DFS 属性。 

因此```
good[v]
=
good[l]
and
good[r]
and
(one of the two arrangements above)
```这个递归条件既是必要的也是充分的。 

## 算法演练

 1. 预先计算子树大小`sz[v]`对于每个顶点。 

由于树是固定且完美的，因此可以使用后序遍历一次完成此操作。 
2. 维护当前的排列和数组`pos`。`pos[x]`存储顶点的当前位置`x`在排列中。 
3. 对于每个顶点，计算`good[v]`从叶子向上。 

叶子总是有效的。 内部节点检查其子节点的两种可能的 DFS 排列。 
4. 维护计数器`bad`等于其顶点的数量`good[v]`是假的。 

整个排列是一个有效的 DFS 顺序，恰好在`bad = 0`。 
5. 当查询交换位置时`x`和`y`，令交换后的顶点为`a`和`b`。 

更新排列并更新`pos[a]`和`pos[b]`。 
6. 收集所有可能受影响的顶点。 

仅有的`a`,`b`，并且他们的祖先可以改变有效性。 没有其他子树看到任何位置变化。 
7. 重新计算`good[v]`对于每个受影响的顶点，先处理较深的顶点，然后再处理较浅的顶点。 

这保证了在重新计算父级时，子级的值已经是正确的。 
8. 调整全局`bad`每当顶点从有效变为无效时计数器，反之亦然。 
9. 输出`"YES"`如果`bad = 0`， 否则`"NO"`。 

### 为什么它有效

 关键的不变量是`good[v]`当子树的顶点恰好为真时`v`形成一个有效的前序 DFS 序列，根为`v`。 

证明是通过子树高度的归纳来实现的。 

一片叶子是平凡有效的。 

假设该声明适用于内部节点的两个子节点`v`。 在任何预购 DFS 中，`v`必须首先出现。 之后，一个子子树完全出现，然后是另一子子树完全出现。 由于子树大小是固定的，所以两个子块的起始位置是完全确定的。 重复中的两个检查与两个可能的儿童探视令完全对应。 

如果任一排列成立并且两个子子树都有效，则`v`是有效的 DFS 订单。 如果两种排列都不成立，则 DFS 无法产生观察到的排序。 

因此，每个节点的递归都是正确的。 当根有效时，整个排列精确有效，这相当于每个局部条件成立，因此`bad = 0`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, q = map(int, input().split())

        parent = [0] * (n + 1)
        arr = list(map(int, input().split()))
        for i in range(2, n + 1):
            parent[i] = arr[i - 2]

        p = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, v in enumerate(p):
            pos[v] = i

        sz = [1] * (n + 1)
        for v in range(n, 0, -1):
            l = v * 2
            r = l + 1
            if l <= n:
                sz[v] += sz[l]
            if r <= n:
                sz[v] += sz[r]

        good = [False] * (n + 1)

        def calc(v):
            l = v * 2
            r = l + 1

            if l > n:
                return True

            pv = pos[v]
            pl = pos[l]
            pr = pos[r]

            option1 = (
                pl == pv + 1 and
                pr == pv + 1 + sz[l]
            )

            option2 = (
                pr == pv + 1 and
                pl == pv + 1 + sz[r]
            )

            return good[l] and good[r] and (option1 or option2)

        bad = 0

        for v in range(n, 0, -1):
            good[v] = calc(v)
            if not good[v]:
                bad += 1

        for _ in range(q):
            x, y = map(int, input().split())
            x -= 1
            y -= 1

            a = p[x]
            b = p[y]

            affected = set()

            cur = a
            while cur:
                affected.add(cur)
                cur = parent[cur]

            cur = b
            while cur:
                affected.add(cur)
                cur = parent[cur]

            for v in affected:
                if not good[v]:
                    bad -= 1

            p[x], p[y] = p[y], p[x]
            pos[a], pos[b] = pos[b], pos[a]

            order = sorted(affected, reverse=True)

            for v in order:
                good[v] = calc(v)

            for v in affected:
                if not good[v]:
                    bad += 1

            print("YES" if bad == 0 else "NO")

if __name__ == "__main__":
    solve()
```读取树和排列后，解决方案构建逆映射`pos`，它允许恒定时间访问任何顶点的当前位置。 

子树大小是自下而上计算的。 因为这棵树是完美的并且存储在堆编号中，所以`v`只是`2v`和`2v+1`。 

功能`calc(v)`实现证明中的递归。 它检查两个子子树是否恰好从预序 DFS 要求的位置开始。 

数组`good`存储每个子树的有效性。 柜台`bad`允许在更新后在恒定时间内回答查询。 

交换仅影响交换的顶点及其祖先。 树的高度最多为 16，因此受影响的集仍然很小。 

顶点按递减的数字顺序重新计算。 在堆编号树中，每个子节点的索引都比其父节点大，因此这自然会在父节点之前处理子节点。 

一个微妙的细节是删除旧的贡献`bad`在重新计算之前并在之后添加新的贡献。 忘记这一步会导致累积计数错误。
