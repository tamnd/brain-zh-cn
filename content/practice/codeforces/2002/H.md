 ## 解决方案
 ## 问题理解

 我们被要求对具有非常特殊的合并属性的整数序列进行计数。 对于给定长度的序列`n`，之间的每个元素`1`和`m`，我们可以重复取三个连续的元素`a_i, a_{i+1}, a_{i+2}`并将它们合并成一个数字，定义为`max(a_i + 1, a_{i+1}, a_{i+2} + 1)`。 问题 101 的目标是执行尽可能多的合并，且结果数量不超过`m`。 

计数 101 提出了一个更高级别的问题：我们不希望计算给定序列的最大合并次数，而是针对每个可能的合并计数`k`从`0`到`floor((n-1)/2)`，长度序列的数量`n`正是达到`k`合并。 

约束条件很小`m`（最多 30 个）且中等`n`（最多 130 个）。 这暗示着一种利用动态规划的方法`n`和`m`值是可行的，因为直接迭代所有序列将是指数级的：`m^n`可以达到`30^130`，这是完全不可行的。 每个测试用例必须输出一个模数计数序列`10^9+7`，这表明计数可能会变大。 

非明显的边缘情况包括以下序列：`n < 3`（不可能进行合并，答案始终是零操作）或序列`m = 1`（值全部为 1，因此只能发生某些合并计数）。 例如，`n = 3, m = 1`仅导致一个序列`[1,1,1]`并且可以进行一次合并，给出输出`0 1`。 不处理小问题的粗心解决方案`n`单独可能会产生索引错误或不正确的计数。 

当最大数量时会发生另一个微妙的情况`m`相比之下非常小`n`，限制可以进行的合并次数。 例如，如果`m = 2`和`n = 5`，不可能执行两次合并，因为第一次合并已经增加了一些数字`3`，这超过了`m`。 任何假设无限制合并的强力方法都会错误地计算这些序列。 

## 方法

 暴力方法会枚举每个可能的长度序列`n`元素来自`1`到`m`，模拟所有可能的合并，并计算每个序列可能有多少次合并。 这在原则上是正确的，但完全不可行：对于`n = 130`和`m = 30`，我们需要处理`30^130`序列。 即使每个序列的模拟也会很昂贵，因为我们需要考虑多个合并位置。 

关键的见解来自于观察合并操作的结构。 合并仅取决于三个连续元素。 如果我们定义一个 DP 状态来跟踪当前位置、完成的合并次数以及最后两个元素的值，我们就可以系统地计算序列的数量，而无需显式枚举它们。 

具体来说，DP可以定义为`dp[pos][k][x][y]`= 到位置的序列数`pos`最后两个元素是`x`和`y`，并且准确地说`k`到目前为止已经执行了合并。 对于下一个元素`z`，我们要么与最后两个元素执行合并（如果`max(x+1, y, z+1) <= m`）或扩展序列而不合并。 迭代所有`x, y, z`值是可行的，因为`m`很小，并且`n`是适中的。 这将指数问题简化为多项式问题。 

通过仔细地将 DP 滚动到位置上并将状态压缩为仅最后两个元素和当前合并计数，我们可以实现实用的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(m^n * n) | O(m^n * n) | O(m^n) | O(m^n) | 太慢了 |
 | 最佳DP | O(n * m^3 * n/2) ≈ O(n^2 * m^3) | O(n * m^3 * n/2) ≈ O(n^2 * m^3) | O(n/2 * m^2) | O(n/2 * m^2) | 已接受 |

 ## 算法演练

 1. 如果需要，预先计算阶乘和模逆，但在此解决方案中，我们通过动态编程避免组合数学。 
2. 初始化3D DP数组`dp[k][x][y]`在哪里`k`是执行的合并次数，并且`x`和`y`是当前序列中的最后两个元素。 放`dp[0][x][y] = 1`对于所有对`(x, y)`如果我们想象长度为 2 的序列。 
3. 从位置 2 迭代到`n-1`（0-索引）。 对于每个 DP 状态`(k, x, y)`，考虑添加一个新元素`z`从 1 到`m`。 计算合并候选者`merge_val = max(x + 1, y, z + 1)`。 如果`merge_val <= m`，然后我们可以执行合并：增量`dp[k+1][y][merge_val]`经过`dp[k][x][y]`。 否则，扩展而不合并：增量`dp[k][y][z]`经过`dp[k][x][y]`。 
4. DP加注至位置后`n-1`, 总和`dp[k][x][y]`对于每个`k`获取长度序列的总数`n`准确地产生`k`合并。 
5. 返回这些计数的模数`10^9+7`。 

为什么它有效：DP 保持每个状态的不变量`(k, x, y)`准确地表示达到最后两个元素配置的序列数`k`合并。 通过系统地考虑下一个元素并考虑合并条件，我们确保所有有效序列都被精确计数一次，并且不包含无效序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve(n, m):
    max_k = (n - 1) // 2
    dp = [[ [0]*(m+2) for _ in range(m+2) ] for _ in range(max_k+2)]
    
    # Base: sequences of length 2
    for x in range(1, m+1):
        for y in range(1, m+1):
            dp[0][x][y] = 1
    
    for pos in range(2, n):
        ndp = [[ [0]*(m+2) for _ in range(m+2) ] for _ in range(max_k+2)]
        for k in range(max_k+1):
            for x in range(1, m+1):
                for y in range(1, m+1):
                    val = dp[k][x][y]
                    if val == 0:
                        continue
                    for z in range(1, m+1):
                        merge_val = max(x+1, y, z+1)
                        if merge_val <= m and k+1 <= max_k:
                            ndp[k+1][y][merge_val] = (ndp[k+1][y][merge_val] + val) % MOD
                        else:
                            ndp[k][y][z] = (ndp[k][y][z] + val) % MOD
        dp = ndp
    
    result = []
    for k in range(max_k+1):
        total = 0
        for x in range(1, m+1):
            for y in range(1, m+1):
                total = (total + dp[k][x][y]) % MOD
        result.append(total)
    return result

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    res = solve(n, m)
    print(' '.join(map(str, res)))
```此代码初始化长度为 2 的序列，然后一次将它们扩展一个位置。 在每个步骤中，它都会考虑合并和非合并转换。 使用两个 3D 数组可以让我们高效地前滚。 每次加法时都会应用模数以防止溢出。 嵌套循环是安全的，因为`m`最多 30 个并且`n`最多130个。
