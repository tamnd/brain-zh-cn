 ## 解决方案
 ## 问题理解

 我们正在处理越来越多的长方形纸币。 每次添加注释时，它都会永远保留。 后来我们收到询问，询问到目前为止看到的所有纸币是否都可以放入给定的矩形钱包内。 

一张纸币可以旋转，所以一张纸币的大小$x \times y$可以被视为任一方向。 一张纸条可以放进钱包里$h \times w$如果在可能旋转后，钞票的两个尺寸均不超过相应的钱包尺寸。 

一个关键的细节是每个音符必须独立适合。 纸币之间不存在打包相互作​​用，因此钱包的条件很简单，就是它必须足够大，可以单独容纳每张纸币。 

每个“add”类型的查询都会插入一个矩形，每个“check”类型的查询都会询问到目前为止所有插入的矩形是否可以单独放入给定的钱包中。 

约束条件达到$5 \cdot 10^5$操作，因此任何扫描每个查询之前所有注释的解决方案都会导致大约$O(n^2)$最坏情况下的行为，速度太慢了。 我们需要只保留少量状态并在恒定时间内回答每个查询的东西。 

当考虑“独立的最大宽度和最大高度”时，会出现一个微妙的陷阱。 但这失败了，因为旋转耦合了维度。 例如，有笔记$100 \times 1$和$1 \times 100$意味着“最大宽度”为 100，“最大高度”为 100，但这并不反映这两个音符实际上已经很好了。 真正的约束取决于每个音符的最佳方向，而不是每个全局轴的选择。 

另一种失败模式来自于试图维护所有音符的边界矩形，就好像它们必须一致对齐一样。 该问题不需要音符之间保持一致的方向； 每个音符都可以独立旋转。 

## 方法

 暴力方法保留所有笔记的列表。 对于类型检查的每个查询，我们都会迭代所有存储的笔记，并测试每个笔记在轮换后是否适合钱包。 这是正确的，因为它直接强制执行定义。 然而，随着高达$5 \cdot 10^5$查询，这会退化为检查$5 \cdot 10^5$每个查询的注释，产生约$10^{11}$在最坏的情况下进行操作，这是不可能的。 

关键的观察是我们不需要跟踪每个矩形。 钱包要失败，必须存在一张不合适的纸币。 因此，我们不必每次都检查所有纸币，而只需维护是否存在至少一张“最差”纸币阻塞钱包即可。 

每个音符$x \times y$可以通过对其边进行排序来标准化，以便$a = \min(x, y)$,$b = \max(x, y)$。 经过此转换后，每个音符都以规范方向表示，其中$a \le b$。 现在有钱包$h \times w$也可以被视为$(\min(h,w), \max(h,w))$。 

当且仅当两者都适用时，注释才合适$a \le h$和$b \le w$。 因此，如果我们确定钱包的候选方向，唯一相关的约束是所有纸币必须位于该角落下方。 

现在重要的简化是：我们不再检查所有笔记，而是维护一个跟踪“最大障碍”的结构。 最差的音符是最大的音符$a$，其中，最大的$b$。 这将约束集减少为仅两个值。 

当查询到达时，我们会根据该对检查钱包的两个方向。 如果两个方向都不支配存储的最大约束，则答案为“否”； 否则是的。 

这是有效的，因为任何可以使钱包失效的票据都必须在某些方向上违反两个维度之一，并且规范表示确保我们只需要测试对极值点的支配性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(n)$| 太慢了 |
 | 维持极值|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们按顺序处理查询，同时维护两个值：所有音符较小边的最大值，以及标准化后较大边的最大值。 

1. 对于每个添加的注释$x, y$, 计算$a = \min(x, y)$,$b = \max(x, y)$。 这消除了方向模糊性，因此每个矩形都可以以一致的方式进行比较。 
2. 维护两个全球价值观：`max_a`作为其中最大的$a$， 和`max_b`作为其中最大的$b$对于笔记实现`max_a`。 这捕获了最受限制的形状。 
3.查询钱包$h, w$，也将其标准化为$h \le w$。 这确保了与存储的笔记进行一致的比较。 
4. 检查钱包是否可以容纳最坏情况的纸币。 这意味着验证两者是否`max_a ≤ h`和`max_b ≤ w`。 
5. 由于钱包的方向也可以调换，所以我们还要检查调换后的情况：`max_a ≤ w`和`max_b ≤ h`。 
6. 如果任一方向有效，我们打印 YES； 否则不。 

### 为什么它有效

 每个音符都被简化为规范对$(a, b)$在哪里$a \le b$。 任何有效的矩形收容都对应于将这一对放入钱包的选定方向。 唯一可能阻碍可行性的注释是至少在一个维度上最难拟合的注释。 跟踪最大值$a$确保我们尊重最紧的“空方”，并跟踪最大的$b$其中确保我们尊重相应的“长边”约束。 任何其他音符都受这些极端值之一的支配，因此如果极端值适合，则所有音符都适合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    max_a = 0
    max_b = 0
    
    for _ in range(n):
        parts = input().split()
        
        if parts[0] == '+':
            x = int(parts[1])
            y = int(parts[2])
            a = min(x, y)
            b = max(x, y)
            
            if a > max_a:
                max_a = a
                max_b = b
            elif a == max_a:
                if b > max_b:
                    max_b = b
        
        else:
            h = int(parts[1])
            w = int(parts[2])
            
            a1, b1 = min(h, w), max(h, w)
            
            ok = (max_a <= a1 and max_b <= b1)
            print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```该代码增量地维护规范的最差矩形。 对于每次插入，它都会更新字典顺序最大的对$(a, b)$，首先最小化短边，然后最大化关系中的长边。 每个查询只是检查这个最差的矩形是否以最佳方向适合钱包。 

一个常见的错误是尝试独立跟踪两个维度的全局最大值。 但这会失败，因为这些最大值可能来自不同的音符，并且无法通过单个矩形同时实现。

 ## 边缘情况

 一种边缘情况是最大的短边与最大的长边来自不同的音符。 该算法处理这个问题是因为`max_b`仅当相应的`a`等于`max_a`，确保两个值都来自兼容的候选者。 

另一个边缘情况是重复更新，仅更改短边最大值。 在这种情况下，必须将长边重置为新候选者的长边； 否则存储的对将与任何真实的矩形不一致。
