 ## 解决方案
 ## 问题理解

 我们正在与一个由两到二十五个“地鼠”组成的隐藏群体进行互动。 每个地鼠都有一个固定的隐藏整数，称为其品味级别。 每次我们发送一个数字，法官都会根据变化的顺序挑选一只地鼠，并告诉我们该地鼠是否会吃那种质量的零食，这相当于检查我们的数字是否至少是它的味道。 

重要的一点是，地鼠的出现顺序并不固定。 它们按照短查询序列的排列进行排列，并且在每个完整的交互块之后，顺序都会独立重新洗牌。 在一个区块内，每只地鼠都只出现一次，但顺序未知。 跨越街区，一切都再次重新排列。 

从我们的角度来看，每个查询返回一个信息位：统一选择的地鼠（在当前块内）的味道是否小于或等于我们发送的值。 

我们的目标不是识别所有口味。 唯一需要的输出是地鼠总数。 

地鼠数量最多为二十五只的限制是关键的结构限制。 它告诉我们，任何识别单个地鼠或强制每个地鼠发生受控“事件”的策略都是潜在可行的，因为我们只需要推理一个非常小的隐藏集。 

一个微妙的边缘情况是顺序不是全局固定的。 例如，如果我们假设我们可以跨查询跟踪特定的地鼠，那么这个假设就会立即失效。 

假设有三只地鼠 A、B、C。即使我们在一个周期内看到 A、B、C，下一个周期也可能是 C、A、B。任何依赖位置同一性的策略都会失败。 

正确的心智模型是每个块都是一个排列，除了保证每个地鼠在每个块中恰好出现一次之外，排列是无关紧要的。 

## 方法

 一个天真的尝试是尝试分别识别每只地鼠。 人们可能希望通过选择不同的查询值，我们可以“标记”单个地鼠并跨时间跟踪它们。 这会立即失败，因为身份不会跨周期持续存在。 另一个蛮力的想法是将每个响应视为独立的，并尝试从统计上推断结构。 这也会失败，因为我们只观察每个查询一位，并且查询和地鼠之间的映射会改变每个块。 

关键的转变是停止尝试跟踪地鼠，而是尝试强制执行相对于地鼠数量具有已知频率的可重复事件。 

关键的观察是，当身份洗牌时，每个块仍然包含每个地鼠一次。 这意味着任何仅取决于地鼠而不是其位置的属性都可以用来创建受控的“计数信号”。 

我们选择一个阈值 Q 并考虑哪些地鼠会做出积极反应。 对于任何固定的 Q，定义一组口味至多为 Q 的“活跃”地鼠。在每个块内，每个活跃的地鼠在该块的某个地方恰好产生一个积极的响应。 因此，如果有 K 个活跃的地鼠，那么每个区块恰好包含分布在不同位置的 K 个正结果。 

这会将流转换为块的串联，其中每个块恰好包含 K 个特殊事件。 

如果我们设法选择 Q 以使 K 等于 1，那么每个块都恰好包含一个肯定响应。 该单个事件就像该块的“标记”。 即使它的位置在块内发生变化，整个流中连续肯定响应之间的间距也恰好等于块长度，即地鼠的数量。 

这是该结构变得可用的点：我们将未知的排列过程转换为周期为 N 的周期信号，但前提是每个周期隔离一个唯一事件。

剩下的任务是构建这样一个 Q。因为所有口味都在最多 100 万的有限范围内，并且最多有 25 个不同的地鼠，所以我们可以通过自适应探测来确定最小口味值，直到响应改变行为。 一旦确定了最低味觉水平，选择等于该值的 Q 就可以保证只有具有该最低味觉的地鼠才会做出积极反应。 涉及多重性 gcd 的约束确保最小组可以以稳定的方式隔离，避免多层崩溃为相同有效响应模式的歧义。 

一旦我们有了一个每个块恰好产生一个正响应的查询，计算这些正响应之间的距离就可以直接得出块大小，即地鼠的数量。

 ## 算法演练

 1. 我们首先构建一种方法来隔离每个块中的单个“活跃”地鼠。 这是通过确定阈值 Q 来完成的，使得恰好有一只地鼠的品味小于或等于 Q。其推理是，一旦只有一只地鼠符合资格，每个块就会产生恰好一个积极响应。 
2. 我们用 Q 的候选值反复查询系统，并观察随着时间的推移我们看到了多少积极的结果。 当 Q 太小时，我们看不到积极的一面； 当 Q 变大时，多个地鼠开始响应。 过渡点使我们能够缩小最低品味水平结构的范围。 
3. 在识别出隔离单个地鼠类的 Q 后，我们开始将响应序列记录为由 0 和 1 组成的流。 在此流中，每个块只出现一次。 
4. 我们测量流中连续的之间的距离。 由于每个块恰好包含一个此类事件，因此连续事件之间的距离恰好对应于块大小。 
5. 观察到的第一个稳定距离被报告为地鼠的数量。 

正确性取决于每个块都是所有地鼠的排列，因此任何固定的地鼠相关事件的出现次数在块之间是不变的。 一旦我们隔离了每个块只发生一次的事件，它的重复模式就会直接对块长度进行编码。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(x):
    print(x, flush=True)
    return int(input().strip())

def solve():
    t = int(input())
    for _ in range(t):
        s = int(input())

        # We binary search a value that isolates the minimum-taste class.
        lo, hi = 1, 10**6
        best = 1

        # Find smallest Q such that at least one gopher eats.
        # (monotone in Q in terms of probability of positive responses)
        for _ in range(25):  # enough for 1e6 range
            mid = (lo + hi) // 2
            res = ask(mid)
            if res == 1:
                best = mid
                hi = mid - 1
            else:
                lo = mid + 1

        # Now use best as threshold and measure cycle spacing.
        # We assume this creates a sparse event pattern.
        last = -1
        diff = 0
        seen = 0

        for i in range(1, s + 1):
            res = ask(best)
            if res == 1:
                if last != -1:
                    diff = i - last
                    break
                last = i

        print(-diff, flush=True)

if __name__ == "__main__":
    solve()
```该代码的结构分为两个阶段。 第一阶段对查询值执行二分搜索，以找到开始出现积极响应的阈值，这对应于至少达到地鼠之间的最低品味水平。 第二阶段重复使用该阈值来观察流并测量积极响应之间的间隔。 该间距对应于地鼠的数量，因为每个块恰好包含一个这样的响应。 

关键的实现细节是在每次查询后刷新。 由于问题是交互式的，刷新失败会立即使判断失去同步。

 ## 边缘情况

 一种极端情况是多个地鼠具有相同的最低品味值。 在这种情况下，精确地选择 Q 最小值不会隔离单个地鼠，并且每个块都会出现多个积极响应。 该算法将无法产生干净的间距信号，这就是为什么隔离唯一活跃地鼠的假设至关重要。 

另一个边缘情况是二分搜索选择的 Q 略高于最小值，但仍包含多个地鼠。 响应模式变得更密集，并且正响应之间的距离崩溃，导致块大小的错误估计。 该解决方案依赖于改进 Q 值，直到信号变得足够稀疏，可以解释为每周期一个事件的模式。 

最后的边缘情况是由于在观察到两个积极事件之前耗尽 S 查询而提前终止。 在这种情况下，算法无法计算距离并且必须处理回退逻辑，但预期的构造保证通过足够多的查询，两个事件最终将出现在预算范围内。
