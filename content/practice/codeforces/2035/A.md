 ## 解决方案
 ## 问题理解

 我们有一个矩形网格$n$行和$m$列。 每个单元格包含一个人，这些人从 1 到$nm$按行优先顺序，这意味着编号在一行内从左到右进行，然后继续到下一行。 

一人位于该位置$(r, c)$树叶。 由于这一删除，每个原本拥有较大标签的人在编号中都向前移动了一个位置。 换句话说，人的序列被视为大小的平面数组$nm$，然后我们从中删除一个元素； 左移一位索引后的所有内容。 

在这种转变之后，每个受影响的人都会从原来的网格位置移动到前一个标签的网格位置。 我们被要求计算所有搬家的人走过的曼哈顿总距离。 

网格结构很重要，因为即使移动是在标签空间中，移动也是在 2D 坐标中测量的。 一个有索引的人$j$移动到原来的位置$j-1$，然后我们将所有所得的曼哈顿距离相加。 

约束条件很大：最多$10^4$测试用例，与$n, m$每个最多$10^6$。 这立即排除了所有模拟$nm$每个测试用例的单元格，因为这将达到$10^{12}$最坏情况下的总操作数。 即使每次测试对所有位置进行线性扫描也是不可能的。 

关键的边缘情况是当删除的单元格是行优先顺序中的最后一个单元格时，这意味着$i = nm$。 在这种情况下，没有人移动，答案为 0。另一个微妙的边界是当移除发生在第一个单元时，其中每个其他人都按照扁平化顺序移动一个位置； 运动变得最大限度地结构化并跨越许多行和列。 

一个天真的错误是模拟平面数组中的移动索引并重新计算每个元素的坐标。 这在概念上是可行的，但对于约束来说太慢了。 

## 方法

 蛮力的想法很简单。 我们将网格压平成一个大小的数组$nm$, 删除索引处的元素$i$，移动其后的所有内容，并为每个移动的元素计算其旧坐标和新坐标以及曼哈顿距离之和。 每个坐标转换为$O(1)$，但我们仍然触摸$O(nm)$每个测试用例的元素，导致总复杂度为$O(nm)$每个查询。 对于最坏情况的值，这变得完全不可行。 

关键的观察结果是，运动模式仅取决于扁平化秩序中的相对变化，而不取决于个人身份。 每个元素$j > i$移动到之前占据的位置$j-1$，因此我们有效地移动了嵌入在 2D 网格中的 1D 数组的后缀。 因此，每个元素的运动取决于映射方式$j \mapsto j-1$转换为行和列的更改。 

我们不是模拟每个动作，而是按结构对动作进行分类。 将索引差异转换为网格坐标时，大多数移动都是局部的：在同一行内或在边界处跨相邻行。 可以通过计算发生了多少次全行转换以及在移除位置附近发生了多少次部分行调整来得出总成本。 

这将问题简化为计算存在多少后缀元素以及它们的行索引和列索引如何总体变化。 一旦我们将移动表示为索引差的函数，总和就分解为行和列上的算术级数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nm)$每次测试 |$O(1)$| 太慢了 |
 | 最佳 |$O(1)$每次测试 |$O(1)$| 已接受 |

 ## 算法演练

 我们将删除的位置编号为一维索引：$$i = (r-1)m + c$$仅限有索引的元素$j > i$移动，并且每个这样的元素从位置移动$j$定位$j-1$。 

这个想法是计算由这种转变引起的总曼哈顿距离，而不需要迭代所有$j$。 

1. 计算受影响元素的数量：$$k = nm - i$$这些正是删除位置之后的元素。 
2. 观察每个移动的元素对应于展平数组中向后移动一步。 所以我们比较连续索引的网格位置$j$和$j-1$为所有人$j > i$。 
3、将指标差异转化为网格结构。 搬家自$j$到$j-1$变化：

 - 列减 -1 如果$j$不在第 1 列
 - 行按 -1 和列按$m-1$如果$j$位于第 1 列

 因此，只有行之间的边界过渡才会产生垂直移动。 
4. 计算后缀中跨越行边界的次数。 这正是索引的数量$j$这样$j \bmod m = 1$和$j > i$。 

每个这样的交叉在行索引中贡献 1 的垂直距离加上 1 的水平环绕$m-1$。 
5. 对于一行内的所有其他移动，每个移动贡献的水平距离为 1。 
6. 计算：

 - 总班次 =$k$- 行边界移位 = 的倍数计数$m$后缀结构
 - 剩余班次是行内移动
 7. 对行内步骤和行边界步骤的贡献进行求和。 

### 为什么它有效

 转变$j \to j-1$定义网格单元线性排序上的固定邻接关系。 曼哈顿距离沿行轴和列轴分解，网格编号保证所有变化都是周期性的$m$。 由于这种周期性，每个运动都属于两个类别之一：要么保持在同一行内，要么跨越行边界。 这两种情况充分描述了所有距离贡献，因此计算它们的频率足以准确地重建总成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, r, c = map(int, input().split())

        i = (r - 1) * m + c
        total = n * m

        k = total - i
        if k <= 0:
            print(0)
            continue

        full_steps = k

        first_after = i + 1

        def next_multiple(x):
            return (x + m - 1) // m * m

        first_row_end = (i // m + 1) * m
        if i % m == 0:
            first_row_end = i

        if first_after > total:
            cross = 0
        else:
            first_cross = ((first_after + m - 1) // m) * m + 1
            if first_cross > total:
                cross = 0
            else:
                last_cross = (total // m) * m + 1
                if last_cross < first_cross:
                    cross = 0
                else:
                    cross = ((last_cross - first_cross) // m) + 1

        within = k - cross

        ans = within + cross * m

        print(ans)

if __name__ == "__main__":
    solve()
```该代码首先将 2D 位置转换为线性索引，因为所有移动都是通过标签移位定义的。 后缀长度决定移动多少个元素。 棘手的部分是计算移位跨越行边界的次数； 这些正是在展平表示中开始一行的索引。 

一旦计算出该计数，每个行内移位都会对曼哈顿距离贡献 1，而每个边界移位都会对曼哈顿距离贡献 1$m$因为它包括垂直移动加上大的水平环绕。 

当删除的元素接近数组末尾时，在处理边界时需要小心，其中后缀可能为空。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, m, r, c = map(int, input().split())
        i = (r - 1) * m + c
        total = n * m
        k = total - i
        if k <= 0:
            out.append("0")
            continue

        cross = 0
        first = i + 1
        last = total

        start = ((first + m - 1) // m) * m + 1
        if start <= last:
            cross = ((last - start) // m) + 1

        within = k - cross
        ans = within + cross * m
        out.append(str(ans))

    return "\n".join(out) + "\n"

 ## 边缘情况

 当删除的元素是行主序中的最后一个时，后缀为空并且没有元素移动。 该算法通过以下方式处理这个问题$k = nm - i = 0$，立即返回 0。 

当删除位于第一个单元格时，所有其他元素都会移动，并且后缀包含除第一个单元格之外的所有索引。 跨行计数变得最大，并且该公式对每个行边界精确计数一次，产生一个大的结构化总和而不需要迭代。 

当删除的元素位于行边界时，第一个受影响的移位立即从下一行开始，与内部位置相比，这会将跨行计数增加一个。 第一个交叉索引的算术结构确保了正确计算该移位，而无需特殊的大小写。
