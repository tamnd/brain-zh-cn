 ## 解决方案
 ## 问题理解

 我们正在研究一个圆形板，分成$k$标记的扇区按顺时针方向排列。 每个数字来自$1$到$n$必须放置在不同的扇区上，并且最终配置必须遵守严格的读取顺序：如果从包含的扇区开始$1$顺时针走，你一定会遇到$2, 3, \dots, n$按照确切的顺序，然后返回$1$。 

每个号码$i$有一组受限制的允许放置的扇区。 有一个杰出的部门$x_i$，从该扇区您可以逆时针移动到$a_i$步数或顺时针方向直至$b_i$步骤。 所以每个$i$实际上具有允许位置的圆形间隔，可能围绕不对称$x_i$。 

任务不是构建一种有效的排列，而是计算有多少种不同的方式为所有数字分配位置，以便满足放置约束和顺时针排序约束。 

限制很小：$n \le 15$,$k \le 60$。 这立即表明指数行为$n$是可以接受的，而任何指数$k$是不必要的或浪费的。 小的$n$强烈暗示我们应该将数字视为一个序列，并在其顺序上使用动态规划，而不是直接在圆上使用。 

一个微妙的问题是结构的圆形性质。 排序条件是循环的，这意味着配置被定义为轮换。 修复序列开始的位置并不是免费的，但它成为线性化圆的有用技术。 

当忽略排序的环绕性质时，就会出现一个幼稚的错误。 例如，如果$k=5$并且选择有效的位置使得$1$位于第 4 区并且$2$在扇区 1，即使从 4 开始的顺时针顺序正确环绕，线性解释也会错误地拒绝这一点。 

另一个常见的失败来自于独立处理每个数字而不强制执行全局排序。 即使每个数字都放置在其允许的间隔内，仍然可能会违反循环排序约束，因为放置可能会在环周围错误地交错。 

## 方法

 直接的暴力方法会尝试所有的分配$n$之间的不同部门$k$，然后检查每个数字是否在其允许的范围内以及顺时针顺序条件是否成立。 选择位置的方法有多种$\binom{k}{n} \cdot n!$，对于每个作业，我们都需要一个验证通过。 这已经变大了$k=60, n=15$， 自从$\binom{60}{15}$是巨大的。 

关键的结构观察是数字的相对顺时针顺序是预先固定的：一旦$1$被选中后，位置$2,3,\dots,n$必须严格按照顺时针递增顺序绕圈。 这完全消除了任何排列自由。 我们不再为选定的扇区任意分配数字，而是选择递增的序列$n$圆上的位置。 

剩下的困难是圆形边界。 一旦我们选择了序列的开始位置，我们就可以在该点“切割”圆并将其视为一条线。 在此切割之后，每个有效配置对应于长度线上严格递增的位置序列$k$，但每个数字仍然有其自己的允许集，这可能会环绕剪切。 这促使尝试每个可能的数字起始位置$1$，将该选择的圆线性化，然后在递增序列上执行简单的 DP。 

这最多可以将问题简化为一个小型动态规划$k$起始点，每个起始点最多有一个序列构建 DP$n \le 15$步骤和$k \le 60$职位。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力作业 |$O(\binom{k}{n} \cdot n!)$|$O(n)$| 太慢了 |
 | 递增序列上的起始点 + DP |$O(k^2 \cdot n)$|$O(k)$| 已接受 |

 ## 算法演练

 我们首先修复循环对称性，然后计算线性解。 

1. 选择一个扇区来托管号码$1$。 这个扇区成为我们顺时针遍历的起点。 通过固定 的位置，每个有效的圆形排列都被精确计数一次$1$，因为旋转有效配置不会改变相对顺序，但会产生不同的起点选择。 
2. 从所选扇区开始将圆展开成直线段。 削减之前顺时针方向的任何部门都被视为指数增加了$k$，所以我们在一个长度范围内工作$k$但允许某些位置表示为$x + k$当它们缠绕时。 
3. 对于每个数字$i$，将其允许的圆间隔转换为展开的线。 根据间隔是否穿过切割，这会变成一个连续的线段或两个线段，但永远不会超过两个，因为间隔长度严格小于$k$。 
4. 按顺序处理数字$1$到$n$，在最后选择的位置上保持 DP。 DP 状态代表我们放置数字的方式有多少种$i$，结束于展开线上的特定坐标。 
5. 对于每个数字$i$, 转换为数字$i+1$通过选择任何允许的位置$i+1$严格位于当前最后一个位置之后。 这会直接在线性化表示中强制执行顺时针排序。 
6. 放置数字后对所有 DP 状态求和$n$。 这将计算所选起始位置的所有有效展示位置$1$。 
7. 对每个可能的起始扇区重复整个过程$1$，并对结果进行累加。 

正确性来自于以下事实：每个有效的圆形配置都有一个独特的旋转，其中扇区$1$被选为剪切。 在此切割之后，顺时针顺序变成展开线中严格递增的顺序，并且每个过渡都尊重明确性和允许的放置约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    x = []
    a = []
    b = []
    for _ in range(n):
        xi, ai, bi = map(int, input().split())
        x.append(xi - 1)
        a.append(ai)
        b.append(bi)

    ans = 0

    for start in range(k):
        # build allowed positions in unrolled line [start, start+k)
        allowed = [[] for _ in range(n)]

        for i in range(n):
            cx = x[i]

            for d in range(-a[i], b[i] + 1):
                pos = (cx + d) % k
                # map into unrolled coordinates
                if pos >= start:
                    u = pos
                else:
                    u = pos + k
                allowed[i].append(u)

            allowed[i] = sorted(set(allowed[i]))

        # dp over last position
        dp = [0] * (2 * k)
        for p in allowed[0]:
            if p >= start:
                dp[p] = 1
            else:
                dp[p + k] = 1

        for i in range(1, n):
            ndp = [0] * (2 * k)
            for last in range(2 * k):
                if dp[last] == 0:
                    continue
                for p in allowed[i]:
                    if p > last:
                        ndp[p] += dp[last]
            dp = ndp

        ans += sum(dp)

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先枚举编号的起始扇区$1$，然后将所有允许的圆形位置转换为一致的线性坐标系。 DP 数组存储了我们可以将数字放置到当前索引的多少种方式，同时保持严格递增的位置。 

关键的实现细节是坐标提升：切割之前的位置移动了$+k$。 这确保顺时针顺序成为整数的简单递增顺序。 条件`p > last`强制执行严格的排序和扇区的唯一性。 

另一个微妙之处是允许集合内的重复数据删除。 没有`set`，同一位置可能会从不同的环绕表示中多次生成，从而人为地夸大计数。

 ## 边缘情况

 关键的边缘情况是当数字的允许间隔环绕剪切位置时。 在这种情况下，同一物理扇区在标准化之前表现为两种不同的表示形式。 里面的重复数据删除步骤`allowed[i]`确保这些重复项不会错误地倍增路径。 如果没有它，通过两条模块化路线可到达的扇区将重复计算每条连续路径，从而夸大最终答案。 

当某个数字的所有有效位置完全位于剪切之前时，就会出现另一种边缘情况。 展开步骤将所有这些移动$+k$，确保它们保持大于之前的位置并且不会错误地破坏顺序。 这保留了以下不变性：无论切割放置在何处，每个有效的顺时针序列都在线上严格递增。
