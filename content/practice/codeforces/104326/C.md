 ## 解决方案
 ## 问题理解

 我们给出了快速排序的确定性变体，其中分区步骤以非常具体的方式编写，并且取决于通过重复调用随机生成器生成的预先选择的枢轴索引序列。 该数组是从 1 到 n 的数字排列，但实际值未知。 已知的是在执行期间将用作主元的索引的确切顺序（按照它们的消耗顺序）。 

分区过程的行为类似于标准的两指针分区，但有一个重要的变化：枢轴是通过索引而不是值选择的，并且在交换期间枢轴位置可以移动。 分区后，枢轴恢复到其最终位置，并且首先在左子数组上继续递归，然后在右子数组上继续递归。 

该函数返回一个与执行期间执行的比较和交换次数成比例的值。 每个分区贡献的成本等于当前段的大小加上递归贡献。 我们的目标是构造 1 到 n 的排列，以便当使用这个精确的主元索引序列时，总返回值最大化。 

约束很小，n ≤ 50，这立即表明子集上的指数或 DP 是可以接受的。 任何试图直接模拟所有可能数组的解决方案都是不可行的，因为有 n！ 排列，但主元序列的结构严重限制了递归树。 

一个微妙的失败案例来自代码中的断言：主元索引必须始终位于当前段内。 如果我们构造一个数组，由于交换移动元素的方式而导致枢轴最终超出其预期的递归范围，则该过程将无效。 仅最大化局部分区成本的天真的贪婪构造很容易违反此结构。 

## 方法

 强力方法会枚举 1 到 n 的所有排列，并使用给定的主元序列模拟每个排列的分区过程。 在最坏的情况下，由于对缩小的段进行重复分区，每次模拟的成本为 O(n^2)，并且有 n！ 排列，即使对于 n = 15 来说也太大了。 

关键的观察结果是，算法的行为完全取决于值相对于每个段的枢轴的分布方式。 每个主元都会将当前区间分为左右子问题。 分区的成本由段大小决定，但递归的正确性取决于所选的主元值在分区后是否处于一致的位置。 

这将问题转化为在索引 1 到 n 上构建二进制递归结构，其中每个节点对应于一个段，并且必须从提供的序列中分配一个主元。 主元序列定义了该递归树的节点“打开”的顺序，这意味着我们可以提前模拟结构并以尊重子树大小的方式分配值。 

最佳策略是重建由主元序列导出的递归树，然后以最大化较高值对较大段的贡献的方式按升序向节点分配值。 由于较大的值应该在递归中出现较高的位置以最大化交换位移，因此我们将分配与遍历顺序约束对齐。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!·n^2) | O(n!·n^2) | O(n) | 太慢了 |
 | 树重建+赋值| O(n^2) | O(n^2) | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 我们模拟如果主元序列有效，快速排序如何划分段，但我们不是处理值，而是处理段结构。

1. 将初始调用视为表示段[1, n]的根节点。 每当第一次处理节点时，主元序列就会按顺序消耗。 这定义了一个二叉递归树，其中每个节点分为左子节点和右子节点。 
2. 对于段 [L, R]，取下一个未使用的主元索引 p。 该枢轴索引属于原始运行中的当前段，因此我们将其指定为该节点的根。 该段分为 [L, p-1] 和 [p+1, R]，形成左子节点和右子节点。 
3. 首先在左段上递归，按顺序消耗主元，然后在右段上递归。 这保留了原始函数的确切执行顺序，其中左递归发生在右递归之前。 
4. 如果在任何时候下一个主元索引不在当前段内，则构造失败，因为原始代码保证主元必须位于活动区间内的断言。 在这种情况下，不存在有效的数组。 
5. 确定树结构后，使用树的中序遍历按升序分配从 1 到 n 的值。 每个节点都会收到一个唯一的值，确保结果是有效的排列。 
6. 通过将每个分配的值放置在其相应的主元位置来形成结果数组。 

### 为什么它有效

 只要每个主元与其段一致，主元序列就完全决定了递归树的形状。 每个节点对应一个唯一的段分区，并且没有两个节点在主元标识上重叠。 一旦结构固定，唯一的自由就是为节点分配值。 由于成本是由段大小和递归结构而不是特定值比较驱动的，因此与树一致的任何有效排列就足够了。 按遍历顺序分配值可确保一致性并避免违反分区约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    pivots = list(map(int, input().split()))
    
    idx = 0
    tree = {}
    pos = [0] * (n + 1)
    
    def build(l, r):
        nonlocal idx
        if l > r:
            return None
        if idx >= n:
            return None
        
        p = pivots[idx]
        if p < l or p > r:
            return None
        
        idx += 1
        tree[p] = [None, None]
        
        left = build(l, p - 1)
        right = build(p + 1, r)
        
        tree[p][0] = left
        tree[p][1] = right
        return p
    
    root = build(1, n)
    
    if idx != n or root is None:
        print("No solution")
        return
    
    val = 1
    
    def assign(u):
        nonlocal val
        if u is None:
            return
        assign(tree[u][0])
        pos[u] = val
        val += 1
        assign(tree[u][1])
    
    assign(root)
    
    print("Solution exists")
    print(*pos[1:])

if __name__ == "__main__":
    solve()
```该解决方案首先重建由主元序列导出的隐式递归树。 每个枢轴索引都根据其当前段进行验证，确保与分区过程的一致性。 如果任何枢轴违反了段约束，则构造立即停止。 

构建树后，我们使用中序遍历分配值，以便每个位置接收从 1 到 n 的唯一值。 最终数组是通过将每个枢轴位置映射到其分配的值来构造的。 

一个微妙的点是，我们必须严格按照递归的前序消耗枢轴：父节点在左子树之前，在右子树之前。 任何偏差都会破坏与原始执行顺序的对齐。 

## 工作示例

 ### 示例 1

 输入：```
3
1 2 3
```| 步骤| 细分 | 枢轴索引 | 行动| 剩余枢轴|
 | ---| ---| ---| ---| ---|
 | 1 | [1,3]| 1 | 根= 1 | [2,3]|
 | 2 | [2,3]| 2 | 1 | 左边 [3] |
 | 3 | [3,3]| 3 | 1 的右边 | []|

 构建树后，中序分配将值 1,2,3 赋予位置 1,2,3。 

输出：```
Solution exists
1 2 3
```这证实了完美增加的主元顺序会产生有效的链状递归树。 

### 示例 2

 输入：```
7
1 7 1 7 1 7 1
```从根来看，主元 1 是有效的。 左子树变空，但下一个主元为 7，这对于递归所期望的剩余结构不再有效。 最终，该序列迫使枢轴进入无效段，导致构造失败。 

输出：```
No solution
```这表明，即使所有值都在全局范围内，快速排序的局部段约束也会使序列无效。

 ## 边缘情况

 大小为 1 的最小输入总是成功，因为除了有效的单个主元之外没有段约束。 

反向或非单调主元序列仅在尊重递归段边界时才有效。 例如，在`2 1 4 3`，第一个主元将范围分成两个有效的独立段，并且后续主元在递归期间正确匹配这些段。 该构造自然地将每个主元放入其正确的子树中，因此分配仍然会成功。 

类似的情况`1 7 1 7 1 7 1`失败是因为分割后，递归期望枢轴保留在逐渐变小的段内，但序列重复引用不再属于活动区间的索引。 当主元失败时，算法会立即检测到这一点`[L, R]`施工时检查。
