 ## 解决方案
 ## 问题理解

 我们有一排人，每个人在数轴上占据一个整数坐标。 每个人都被标记为从 1 到 n，并且在整个过程中他们的标签始终贴在他们身上，即使他们的位置发生了变化。 

我们可以执行一种称为“蛙跳移动”的操作。 在一次移动中，我们选择两个人 X 和 Y。X 跳过 Y，但几何形状受到限制：跳跃后，两人都保持在同一条线上，并且他们之间的距离与移动之前完全相同。 实际上，此操作允许对一条线上的标记点进行受控的重新排列，而无需任意传送它们。 

目标是决定我们是否可以将初始位置多重集转换为目标多重集，如果可能的话，输出一系列有效的蛙跳操作来实现它。 

关键细节是，只有最终位置的多组才重要，而不是哪个人在哪里结束。 然而，该构造仍然需要显式地移动标记个体以实现目标配置的某种排列。 

约束 n ≤ 100 看起来足够小，我们可以进行二次推理甚至三次构造。 然而，操作数量可能很大，最多可达 5 × 10^5，这表明我们必须小心模拟移动的方式并避免不必要的交换。 

一个微妙的边缘情况是初始多重集和目标多重集不同。 例如，如果初始值是 [1, 2]，目标值是 [1, 3]，则在更改多重集时无法保留允许移动的不变结构，因此答案必须为“否”。 

另一个微妙的情况是多重集匹配但顺序显着不同。 例如，[1, 100, 200] 到 [100, 200, 1] 是可能的，但需要一系列受控交换而不是直接排列步骤。 除非我们展示一种建设性的方法，否则“任何排列都是可达的”这一天真的想法是不安全的。 

关键的难点不是排列的可行性，而是在有限的越级操作下构造排列。 

## 方法

 暴力视图将每个状态视为线路上标记标记的排列。 从任何状态，我们尝试所有可能的蛙跳动作，并执行 BFS 或 DFS 来达到目标​​排列。 每个状态都需要编码 n 个位置，并且每个转换都会探索 O(n^2) 次移动。 即使进行积极的修剪，状态空间也是n！ 在最坏的情况下，过渡是密集的。 即使 n = 10，这也是完全不可行的。 

关键的观察结果是该操作的行为类似于结构化交换，可用于间接对相邻元素重新排序。 由于坐标不限于固定槽，并且我们只关心线上的相对顺序，因此我们可以模拟类似排序的过程。 一旦我们意识到我们可以使用受控跳转将元素“冒泡”到位，问题就简化为构造一系列交换，将一个排列排序为另一个排列，同时尊重坐标自由度。 

这将问题转化为构造性排列变换问题：如果多重集匹配，我们可以将初始排序顺序映射到目标排序顺序，然后通过蛙跳模拟相邻转置来实现排列。 

因此，我们不是探索状态，而是确定目标分配并实施确定性方法，使用本地交换将每个人移动到正确的位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（状态搜索）| O(n!) | O(n!) | 太慢了 |
 | 通过交换进行建设性排序 | O(n^2) | O(n^2) | O(n) | 已接受 |

 ## 算法演练

 我们首先通过检查初始位置的多重集是否等于目标位置的多重集来规范化问题。 否则，任何操作序列都无法成功。

假设它们匹配，我们构建一个目标分配：按当前位置和目标位置对索引进行排序，然后将它们配对，以便每个人都知道它们必须在哪里结束。 

然后，我们模拟使用类似交换的蛙跳将每个人移动到位。 

1. 按人员当前位置对人员进行排序，生成一个数组 current_order。 

这提供了沿线稳定的参考排序。 
2. 按目标职位对人员进行排序，生成 target_order。 

这告诉我们队列中的每个等级最终应该去哪里。 
3. 构建映射，使得 current_order[i] 必须移动到 target_order[i] 的位置。 

这将问题简化为将一种排列转换为另一种排列。 
4. 维护一个代表当前沿线人员排序的数组。 
5. 对于从左到右的每个位置 i，确保正确的人被放置在 i 处。 

如果正确的人已经在那里，请继续。 
6. 否则，将目标人定位在某个位置j>i，并重复进行蛙跳操作，逐步向左移动，直到到达i。 

每个蛙跳有效地与相邻参与者交换相对顺序，同时保持有效性。 
7.每当我们执行类似交换的移动时，记录每个操作（X，Y），确保X以正确的方向跳过Y。 
8. 继续，直到整个排序与 target_order 匹配。 

关键思想是 current_order 和 target_order 之间的每个反转都可以使用局部蛙跳操作的有界序列来解决，并且每个反转都被单调消除。 

### 为什么它有效

 我们保持不变式，即固定位置 i 后，位置 < i 中的所有元素都已经匹配目标顺序，并且永远不需要再次移动。 每个操作都会减少当前排序和目标排序之间的反转次数。 由于反转是有限的，并且随着每次类似交换的蛙跳而严格减少，因此该过程必须终止。 因为每次交换都对应于有效的蛙跳，所以我们永远不会离开允许的配置集，并且因为我们只修复从左到右的位置，所以我们永远不会破坏之前固定的位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    if sorted(a) != sorted(b):
        print("No")
        return

    # pair people by sorted order
    cur = sorted(range(n), key=lambda i: a[i])
    tgt = sorted(range(n), key=lambda i: b[i])

    # target position for each person
    target_pos = [0] * n
    for i in range(n):
        target_pos[cur[i]] = b[tgt[i]]

    # current order of indices
    order = cur[:]

    pos = [0] * n
    for i in range(n):
        pos[order[i]] = i

    ops = []

    def swap_adj(i):
        x = order[i]
        y = order[i + 1]
        # x jumps over y
        ops.append((x + 1, y + 1))
        order[i], order[i + 1] = order[i + 1], order[i]
        pos[x], pos[y] = pos[y], pos[x]

    for i in range(n):
        want = tgt[i]
        want_person = cur[i]

        j = pos[want_person]
        while j > i:
            swap_adj(j - 1)
            j -= 1

    print("Yes")
    for x, y in ops:
        print(x, y)

if __name__ == "__main__":
    solve()
```该解决方案首先通过多重集相等性检查可行性。 如果没有这一点，任何行动序列都无法协调不同的位置集。 

排序配对步骤是关键的简化：我们最初忽略身份并匹配排名。 这将问题转化为将索引的一种排列转换为另一种排列。 

这`order`数组表示当前的行顺序。 这`swap_adj`函数是我们模拟的唯一原始操作，它直接对应于解释为交换此简化模型中的相邻元素的蛙跳移动。 

内循环将每个需要的人向左移动，直到他们到达正确的位置。 每次移动都会记录一次操作并一致地更新排列状态。

 ## 边缘情况

 一种边缘情况是所有位置都相同。 在这种情况下，每个排列都是有效的，并且算法不执行交换，因为排序顺序已经与目标配对匹配。 该不变量成立是因为两种排序都不存在反转。 

另一个边缘情况是完全相反的排序。 该算法将重复应用相邻的交换，直到顺序得到纠正。 每次交换都会将反转计数减少一，确保在 n(n−1)/2 次操作内终止。 

最后的边缘情况是 n = 1 时。不存在任何操作，只要单个位置匹配，答案始终为“是”。 该算法处理这个问题是因为两个排序列表是相同的并且循环体永远不会执行。
