 ## 解决方案
 ## 问题理解

 我们观察到一只蜜蜂与小熊维尼在同一平面上移动，而小熊维尼则以恒定速度沿直线移动。 从固定的外部框架来看，维尼只是一个线性移动的点。 蜜蜂从距 Pooh 已知的距离处开始，然后在两个同时发生的效应下进化：它以固定的角速度绕 Pooh 旋转，同时它与 Pooh 的距离以恒定的线性速率缩小。 

我们被要求计算的不是蜜蜂的最终位置，而是蜜蜂到达维尼那一刻之前所追踪的总路径长度。 换句话说，我们必须将蜜蜂的瞬时速度随时间积分，该速度来自切向旋转和径向运动。 

每个测试用例提供初始分离、维尼的线速度、蜜蜂的径向接近速度和角速度。 答案是蜜蜂轨迹的弧长，直到径向距离变为零。 

这些约束足够小，任何涉及非常精细的时间步长的直接模拟的解决方案都是可行的，但有风险。 关键的困难在于运动是连续且耦合的：旋转发生在以 Pooh 为中心的极坐标中，但 Pooh 本身沿直线运动，因此我们不能将蜜蜂视为围绕固定原点的简单极运动而不考虑 Pooh 引起的相对运动。 

一种简单的方法是以小增量模拟时间，更新维尼的位置，更新蜜蜂的极坐标，重新计算速度分量，并对行驶的距离求和。 但这会失败，因为停止时间可能需要极细的分辨率才能满足所需的精度，特别是当角速度很大或径向收缩很慢时。 

如果我们试图完全忽略维尼的运动，就会出现第二种故障模式。 在维尼的移动坐标系中，蜜蜂的径向速度是给定的，但切向分量并不独立于维尼的平移，因此将其视为围绕固定中心的简单螺旋会导致弧长不正确。 

第三个微妙的问题是碰撞时刻附近。 径向距离接近于零，方向或速度上的任何离散化误差都会在累积弧长中产生较大的相对误差。 

## 方法

 蛮力的观点是及时模拟系统。 在每个小步长 dt 处，我们通过减去 V_bee * dt 来更新径向距离 r，通过添加 Ω_bee * dt 来更新角位置，计算蜜蜂相对于 Pooh 的笛卡尔速度，并累积欧几里得位移。 如果 dt 足够小，则这会逼近真实曲线。 然而，由于当 r 为零时运动结束，并且 r 可以平滑收缩最多 100 个单位，因此实现 1e-4 精度需要非常多的步数，很容易超出时间限制。 

关键的观察是我们实际上并不需要维尼的绝对运动。 在维尼的参考系中，蜜蜂的运动干净地分解为两个正交分量：恒定幅度 V_bee 的径向向内运动，以及由半径 r 处的角速度 Ω_bee 引起的切向运动。 当我们考虑相对运动时，维尼的平移就抵消了。 

这会将轨迹转换为极坐标中具有已知径向衰减的确定性螺旋。 在任意时刻t，半径与时间成线性关系，切向速度与半径成正比。 这意味着总速度是时间的简单函数，并且路径长度减少为标量表达式上的单个积分。 

我们使用 dr = -V_bee dt 将时间积分转换为半径积分。 这完全消除了时间，并将 r 函数从 R 积分到 0 的问题减少。生成的表达式成为 sqrt(V_bee^2 + (Ω_bee * r)^2) 关于 r 的闭式积分，并适当缩放。

这是核心简化：我们不是模拟二维曲线，而是对速度矢量的大小进行积分，该速度矢量的分量是正交的，其中之一与半径线性相关。

 ## 算法演练

 1. 对于每个测试用例，读取初始半径 R、径向速度 V_bee 和角速度 Ω_bee。 这些完全决定了以蜜蜂为中心的极地系统中的运动，因此不需要额外的状态。 
2. 将蜜蜂的瞬时速度大小表示为两个垂直分量的组合。 径向分量具有恒定大小V_bee。 切向分量等于 Ω_bee 乘以当前半径，因为角速度转换为沿圆的线速度。 
3. 将半径 r 处的总速度写为 sqrt(V_bee^2 + (Ω_bee * r)^2)。 这是根据极坐标中径向和切向的正交性得出的。 
4. 使用 dt = -dr / V_bee 将时间积分转换为半径积分。 这种替换消除了时间作为变量，并确保 r 从 R 到 0 的单调积分。 
5. 弧长变为 r 对 sqrt(V_bee^2 + (Ω_bee * r)^2) / V_bee 的积分。 
6. 使用 sqrt(a^2 + b^2 r^2) 的标准反导数计算该积分，产生涉及代数和对数项的封闭形式表达式。 
7. 仔细计算浮点最终值，确保稳定计算接近零的边界值的对数和平方根。 

### 为什么它有效

 正确性取决于以维尼为中心的极坐标中表示蜜蜂的运动。 在该框架中，径向方向和切向方向始终保持正交，因此瞬时速度分解为独立的垂直分量。 由于弧长仅取决于速度的大小，而不取决于方向，因此我们可以通过毕达哥拉斯来处理这些分量。 

假设径向速度是恒定的，角速度产生与半径成比例的切向速度。 由于半径确定性且单调地演化，因此轨迹长度减少为对单个变量的标量函数进行积分。 一旦以极坐标形式表达，就不再存在隐藏的耦合。 

## Python 解决方案```python
import sys
import math
input = sys.stdin.readline

def solve_case(R, Vp, Vb, w):
    # Vp does not affect relative motion in Pooh's frame for path length
    # radial speed is Vb, tangential speed is w * r
    # integrand: sqrt(Vb^2 + (w r)^2) / Vb dr-integral form

    a = Vb
    b = w

    # integral of sqrt(a^2 + (b r)^2) dr
    def F(r):
        # standard formula:
        # (r/2)*sqrt(a^2 + b^2 r^2) + (a^2/(2b)) * asinh(b r / a)
        if b == 0:
            return a * r
        term1 = 0.5 * r * math.sqrt(a*a + b*b*r*r)
        term2 = (a*a / (2*b)) * math.asinh((b*r)/a)
        return term1 + term2

    if b == 0:
        # straight radial motion
        return R

    return (F(R) - F(0)) / Vb

def main():
    T = int(input())
    out = []
    for _ in range(T):
        R, Vp, Vb, w = map(int, input().split())
        out.append(str(solve_case(R, Vp, Vb, w)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该实现将积分评估隔离到辅助函数中，以便易于推理数值稳定性。 该术语使用`asinh`是出现在二次平方根的标准积分中的对数原语的稳定形式。 

一个微妙的点是处理角速度为零时的情况。 在这种情况下，运动退化为纯径向运动，因此轨迹长度恰好等于 R，因为蜜蜂以恒定速度直线朝 Pooh 移动，没有任何切向分量。 

出现除以 Vb 的原因是我们将 dt 转换为 dr。 这就是许多不正确的实现出错的地方：忘记径向速度重新调整整个弧长积分。

 ## 边缘情况

 一个关键的边缘情况是零角速度。 轨迹不再是螺旋线而是直线段。 在这种情况下，一般积分在代数上仍然有效，但在数值上它变得不稳定，因为 asinh 项涉及除以零。 该实现明确地短路了这种情况并返回 R。 

另一个边缘情况是 V_bee 相对于 Ω_bee * r 非常小。 在这种情况下，切向运动占主导地位，被积函数在 r 中几乎呈线性。 基于 asinh 的公式保持稳定，因为它呈对数增长，防止溢出。 

最后，当R为1时，整个轨迹被限制在一个小区域内，F(R) - F(0)中会出现浮点抵消。 使用直接反导数而不是数值积分可以避免累积的离散化误差并保留精度保证。
