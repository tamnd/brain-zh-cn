 ## 解决方案
 ## 问题理解

 我们得到一个对象集合，其中每个对象都有一个数值和对其他对象的引用的固定有序列表。 引用形成有向结构，并且该结构可以包括循环。 任务是将所有对象划分为等价类，其中如果两个对象的“完全扩展结构”相同，则它们属于同一类，这意味着它们的标量值相等，并且它们的引用列表指向本身以相同顺序等价的对象。 

更具体地说，每个对象都由标签和子对象序列定义，如果两个对象的有根有向图（保留子对象的顺序）在子结构相等的情况下同构，则它们是相同的。 

困难在于引用可以形成循环。 这意味着该结构不是树，因此子树的简单递归比较不会终止，除非我们以某种方式打破依赖循环。 

输入大小最多为 100,000 个对象，每个对象最多有 10 个引用。 这立即排除了任何从结构上比较每对对象的方法。 成对比较方法的复杂度为 O(n²)，在最坏的情况下大约需要 10^10 次比较，远远超出了可行的限制。 即使是重复重新计算子结构哈希的每个对象的简单递归哈希也会由于重复遍历共享子图而爆炸。 

当循环存在时，会出现微妙的边缘情况。 例如，对象 A 可能引用 B，而 B 可能引用 A。简单的 DFS 哈希计算将无限递归，或者需要临时记忆，而如果没有全局协调，则很难正确设计。 

另一个边缘情况是多个相同的子结构出现在不同的索引处。 尽管它们在结构上相同，但它们必须接收相同的类，并且即使在不同的遍历顺序中发现，这种相等性也必须一致。 

## 方法

 一个强力的想法是定义每个对象的递归“序列化”：将对象表示为由其标量值和序列化子级列表组成的元组，然后比较这些元组是否相等。 如果我们自下而上地计算，我们可以对每个结构进行散列，然后对相同的散列进行分组。 

然而，这种方法在存在循环的情况下会失败。 不存在自然的自下而上的顺序，因为不能保证依赖关系形成 DAG。 尝试递归计算哈希会导致无限递归或重复重新计算。 即使我们引入记忆化，我们仍然面临循环依赖问题，即 A 的哈希值依赖于 B，反之亦然，并且两者都不能独立完成。 

关键的观察是，我们实际上不需要在结构评估期间解决循环问题。 我们只需要所有节点上一致的等价关系。 这正是一个图分区细化问题：我们希望为每个节点分配一个稳定的标识符，以便两个节点共享相同的标识符，当且仅当它们的标量值和按其邻居标识符的结构排序的多重集匹配时。 

这表明了一个迭代的稳定过程。 我们首先根据每个节点的标量值给每个节点一个初始标签。 然后，我们通过考虑由节点标量值形成的元组及其引用对象的当前标签序列来重复细化标签。 每次迭代都会将这些元组压缩为新的唯一标识符。 因为标签仅依赖于先前的标签，所以循环不会导致问题，因为我们不是递归而是迭代。

这本质上是对图标记函数的定点计算。 由于该图最多有 100k 个节点，每个节点最多有 10 条边，因此每个细化步骤的输入大小都是线性的。 在实践中，所需的迭代次数很少，因为每次迭代都严格细化或稳定等价类，并且状态空间受节点数量限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力递归哈希 | O(n² + 递归开销) | O(n) | 由于循环太慢/不正确 |
 | 迭代标签细化 | O(k·n log n) | O(k·n log n) | O(n) | 已接受 |

 这里 k 是稳定之前的细化轮数，通常很小。 

## 算法演练

 我们将每个对象视为有向图中的一个节点，其中边保留顺序。 每个节点都带有一个值和一个传出边列表。 

1. 为每个节点分配一个等于其标量值的初始标签。 这给出了粗略分组，其中仅相同的值被认为是相等的。 
2. 为每个节点构建一个签名，该签名由其标量值和按顺序引用的节点的当前标签组成。 该签名表示在当前近似相等的情况下对象的当前“视图”。 
3. 对这些签名进行排序或散列以分配新的紧凑标识符。 具有相同签名的节点会收到相同的新标签。 这一步本质上是将结构信息压缩为等价类。 
4. 使用更新的标签重复构建签名，直到标签在迭代之间停止变化。 当标签没有变化时，我们就达到了结构等价稳定的固定点。 
5. 输出每个节点的最终标签作为其类标识符。 

我们依赖迭代而不是递归的原因是循环阻止了明确定义的评估顺序。 迭代在全局范围内传播约束，允许信息循环流动，直到达到一致性。 

### 为什么它有效

 关键的不变量是，每次迭代后，如果两个节点共享相同的标签，则它们的标量值相等，并且它们的邻居标签在前一次迭代中按顺序匹配。 这确保标签只会变得更具辨别力或保持稳定。 由于节点数量有限，因此细化过程无法无限地继续，并最终达到无法进一步细化的程度。 在这一点上，标签的相等与结构等价完全一致，因为任何结构差异都会在某些迭代中产生不同的签名。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    val = [0] * n
    adj = [[] for _ in range(n)]

    for i in range(n):
        parts = list(map(int, input().split()))
        val[i] = parts[0]
        m = parts[1]
        adj[i] = [x - 1 for x in parts[2:]]

    # initial labels based on scalar value
    label = val[:]

    while True:
        sig_map = {}
        new_label = [0] * n
        cur_id = 1

        for i in range(n):
            sig = (label[i], tuple(label[v] for v in adj[i]))
            if sig not in sig_map:
                sig_map[sig] = cur_id
                cur_id += 1
            new_label[i] = sig_map[sig]

        if new_label == label:
            break
        label = new_label

    print(*label)

if __name__ == "__main__":
    solve()
```该实现维护一个近似结构同一性的标签数组。 每次迭代都会构造一个由当前标签和邻居标签的有序列表组成的元组签名。 Python 元组直接用作字典键来唯一标识结构状态。 

停止条件检查迭代中标签的稳定性。 这保证了不可能进一步细化，这意味着所有可区分的结构都已被分离。 

一个微妙的一点是我们不尝试任何 DFS 或递归。 每次迭代都会同时解决所有依赖关系，这避免了循环图中的无限循环。

 ## 边缘情况

 节点之间的直接循环是自然处理的，因为每次迭代都将邻居标签视为已在上一步中定义的。 在双节点相互引用的情况下，两个节点都是相同的，因此它们永远保持相同的签名，这正确地为它们分配了相同的类。 

自引用节点的行为类似。 指向自身的节点会生成一个签名，其中将其当前标签包含在其自己的邻居列表中。 由于两个节点在每次迭代中都比较相等，因此固定点立即稳定。 

具有相同参考模式的大量相同对象会在一次或两次迭代中分解为单个类，因为它们的签名在每个细化阶段都保持相同，从而防止不必要的分裂。
