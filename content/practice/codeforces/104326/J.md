 ## 解决方案
 ## 问题理解

 我们得到一组正整数，每个正整数最多包含六位小数。 我们可以从这个列表中重复选择数字并形成长度最多为 108 个元素的序列。 所选序列的分数不是通过正常加法计算的。 相反，我们将数字逐位相加，并且每个数字位置独立地以 10 为模。 这意味着数字之间没有进位，并且每列的行为就像一个独立的模和。 

任务是仅使用给定的数字构造一个序列，使得当解释为普通整数时，所得的数字总和尽可能大。 在所有可能的序列中，我们必须输出可实现的最大数字和值，然后输出序列的长度，然后输出一个实现它的有效序列。 

关键约束是上限 n 最多 100000，这会立即排除任何指数子集搜索或对值子集的动态编程。 我们必须利用结构来了解数字求和在重复情况下的表现。 

一个微妙的边缘情况源于这样一个事实：我们可以任意多次重复元素，但输出序列长度上限为 108。这个上限不足以独立地强制每个数字的分布。 另一个边缘情况是，即使输入中出现其他数字，最佳解决方案也可能需要多次重复相同的数字，因为数字加法在每个位置上的行为都是独立的，而重复是放大贡献的唯一方法。 

一种幼稚的方法可能会尝试长度不超过 108 的所有可能序列，或者尝试每一步进行贪婪选择。 这会失败，因为早期的贪婪选择会永久限制其他位置的数字积累，并且状态空间太大而无法探索。 

## 方法

 核心困难在于数字加法解耦了数字位置，但约束再次将它们耦合在一起：每个选定的数字同时对所有数字位置做出贡献。 这就产生了一种权衡，即选择对一个数字有利的数字可能会损害另一个数字。 

强力解释会将其视为选择最多 108 个元素的多重集并计算所有可能的数字总和。 即使我们忽略排序，这仍然是从 n 个类型中选择一个重复最多 108 次的多重集，这会导致一个天文数字般大的组合空间，大约为$\binom{n + 108}{108}$，这远远超出了任何可行的计算。 

关键的见解是，模 10 的数字加法具有周期性结构，并且相同数字的重复加法通过数字贡献独立地循环。 我们不应该考虑任意序列，而应该考虑每个候选数字在重复使用中可以做出什么贡献。 

如果我们固定一个数字 x，那么使用它 k 次就会在每个位置贡献 k 乘以它的数字模 10 的值。 由于 k 最多为 108，并且 108 模 10 结构每 10 重复一次，因此有效行为取决于数字在重复周期下如何累积。 这强烈表明，最优结构将大量重用单个最佳数字或小型结构化组合，因为混合不同的数字模式不会在模 10 加法下产生协同作用，它只会重新分配固定的贡献。 

问题归结为确定重复时哪个数字对最高有效数字位置产生最强的增量效应，然后构建一个最大化最终字典数字总和的序列。 

第二个观察结果是，由于输出被解释为普通整数，因此较高的数字占主导地位。 这迫使我们优先考虑首先最大化最高有效数字，然后是下一个，依此类推。 因为所有操作都是独立地对每个数字进行模 10，所以我们可以在控制重复计数的同时逐位模拟贡献。 

这导致了一个最佳的构造，我们按数字方式选择最佳候选，然后通过重复填充序列，如果需要满足精确的模块化目标，则进行小的调整。

 ## 算法演练

 关键思想是，我们将每个数字评估为“数字贡献向量”，并确定哪个向量在重复达到允许的限制时给出最佳回报。 

1. 读取所有数字并将每个数字转换为 6 位向量（如果需要，用前导零填充）。 这让我们可以统一处理数字位置上的所有数字。 
2. 对于每个数字，计算其数字向量贡献。 贡献就是它的数字，因为重复会独立地将每个数字的贡献乘以模 10。 
3. 确定对最高数字位置提供最佳改进的数字。 我们通过按字典顺序从最高有效数字到最低有效数字比较数字来做到这一点。 它们不同的第一个位置确定哪个数字更好，因为该数字主导最终的整数值。 
4. 一旦确定了最佳数字，就确定我们应该使用它多少次。 由于每次使用都会独立地以 10 为模增加数字，并且我们希望最大化最终的数字总和，因此我们使用允许的最大重复次数，即 108，除​​非较小的循环在较低的数字中创建更好的对齐。 
5. 通过重复所选数字 m 次来构建序列。 
6. 通过对每个位置的数字求模 10 来显式计算结果数字总和。 
7. 输出通过连​​接结果数字形成的最终整数，后跟 m，再跟序列。 

### 为什么它有效

 正确性依赖于这样一个事实：每个操作都会贡献一个固定的数字向量，并且加法是按分量模 10 进行的。这意味着除了共享元素选择之外，数字位置之间不存在交互。 不同数字的任何混合都相当于独立地对它们的数字向量求和，因此总结果仅取决于每个所选数字的聚合计数。 由于输出是按数字重要性按字典顺序解释的，因此最佳策略始终优先考虑首先最大化较高的数字位置，这是通过选择按字典顺序最大的数字向量并尽可能重复它来实现的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def digits(x):
    s = str(x).rjust(6, '0')
    return [int(c) for c in s]

def main():
    n = int(input())
    arr = [int(input()) for _ in range(n)]
    
    best = arr[0]
    best_vec = digits(best)
    
    for x in arr:
        v = digits(x)
        if v > best_vec:
            best_vec = v
            best = x
    
    # we can use up to 108 copies
    m = 108
    
    # compute digitwise sum mod 10
    vec = [0] * 6
    for _ in range(m):
        dv = best_vec
        for i in range(6):
            vec[i] = (vec[i] + dv[i]) % 10
    
    # build output number
    res = int("".join(map(str, vec))).lstrip("0")
    if res == "":
        res = "0"
    
    print(res)
    print(m)
    print(" ".join([str(best)] * m))

if __name__ == "__main__":
    main()
```该实现首先将每个数字转换为固定宽度的数字表示形式，以便比较成为数字向量上的字典顺序。 最佳数字的选择是在 n 的线性时间内完成的。 

序列构造简单地重复该数字 108 次，这符合最大允许长度约束。 数字总和是按每个数字以 10 为模显式计算的。 这完全避免了任何进位处理，这是问题的核心简化。 

一个微妙的细节是填充到六位数。 如果没有填充，词典比较将不正确，因为较短的数字在数字意义上会不一致。 填充确保所有向量在同一位置系统中具有可比性。

 ## 边缘情况

 一种边缘情况是所有数字都相同。 在这种情况下，算法不应尝试超出第一次比较的任何选择逻辑。 数字向量保持不变，并且重复加法的行为是可预测的。 例如，输入`3 / 7 7 7`产生一个恒定的最佳向量，重复将其简单地累加 108 次，而无需任何分支决策。 

另一种极端情况是数字仅在低位数字上有所不同。 例如，`120`和`119`。 字典顺序比较可确保选择 120，因为最右侧的第一个不同数字决定了主导地位。 该算法可以正确处理此问题，因为矢量比较尊重位置重要性。 

最后的边缘情况是最佳数字在其填充表示中具有前导零。 这不会影响比较，因为前导零仅出现在较高位置，其重要性低于较低位置的任何非零数字，从而保留了选择的正确性。
