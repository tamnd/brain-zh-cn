 ## 解决方案
 ## 问题理解

 我们得到两个大写字符串，一个代表杰夫当前的产品名称，另一个代表竞争对手的产品名称。 我们可以通过交换杰夫字符串中最多一对字符来改进他的名字。 我们也可以选择什么都不做。 在此操作之后，结果字符串必须严格按照字典顺序小于竞争对手的字符串，否则我们必须报告这是不可能的。 

密钥操作极为有限：仅允许一次交换。 这立即限制了解决方案空间。 如果字符串长度为 n，则可能的交换次数大约为 n(n−1)/2，并且每次与竞争对手字符串的比较成本为 O(n)，这将导致在最坏情况下每次测试的行为为 O(n3)。 所有测试的总长度都以 5000 为界，O(n²) 解决方案是可以接受的，但任何立方体都不可以。 

字典顺序条件引入了前缀敏感的比较。 如果候选字符串较早地与具有较小字符的竞争者字符串不同，或者如果它成为正确的前缀，则该候选字符串更好。 这意味着只有最早的不同立场对大多数决策来说才重要。 

一些边缘情况很重要。 

如果 Jeff 的字符串按字典顺序已经小于竞争对手的字符串，则最佳操作可能是不执行任何操作。 例如，s =“ABC”，c =“ABD”。 任何交换实际上都可能使字符串恶化，因此正确的输出只是“ABC”。 

如果 s 中的所有字符都相同，则任何交换都不会改变任何内容。 如果 s 尚未小于 c，则不存在解。 例如，s =“ZZZ”，c =“AAA”显然无法改进。 

当交换只能通过更改后面的位置来使字符串更小，但使前面的位置更糟时，就会出现一种微妙的情况。 例如，如果后缀损坏了与 c 的第一个不匹配，则改进后缀是没有用的。 

## 方法

 蛮力的想法很简单。 尝试每对索引 i 和 j（包括不交换的选项），构造结果字符串，并将其与 c 进行比较。 这正确地探索了所有可能性，因为约束最多是一次交换。 然而，这探索了 O(n²) 交换，并且每次比较的成本为 O(n)，在最坏的情况下每次测试的总成本为 O(n³)。 总长度达到 5000，这太慢了。 

关键的观察是我们不需要评估所有互换。 字典顺序比较是在字符串不同的第一个位置决定的。 这意味着我们希望使 s 中最早可能的位置严格小于 c，同时保持所有早期位置不变。 

因此，我们不再考虑任意交换，而是贪婪地思考。 我们从左到右扫描并识别第一个索引 i，其中 s[i] 与 c[i] 相比还不是最优的。 在这个位置，我们想要字符串中后面出现的尽可能最小的字符，并且我们希望通过交换将其向前移动。 

正确的策略是：尝试使第一个不匹配位置尽可能小，并在改善该位置的所有交换中，选择一个产生字典顺序最小的结果字符串的交换。 这将问题简化为检查每个位置是否可以找到一个较小的字符来交换。 

我们维护最佳候选交换，以提高最早的位置并产生有效的字典顺序较小的字符串。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（所有交换）| O(n3) | O(n) | 太慢了|
 | 贪婪最佳交换| O(n²) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。

1. 首先，检查 s 是否已经按字典顺序小于 c，且没有进行任何交换。 如果是，则立即输出s。 这是可行的，因为任何交换都是可选的，并且不需要恶化字符串。 
2. 否则，我们尝试最多使用一次交换来构造一个更好的字符串。 我们从左到右扫描每个位置 i 作为潜在的第一个不匹配。 
3. 对于每个位置 i，我们尝试找到一个位置 j > i，使得交换 s[i] 和 s[j] 使得结果字符串按字典顺序小于 c。 最好的候选者是在交换后给出尽可能小的 s[i] 的候选者，因为较早的字符主导字典顺序。 
4. 对于每个 i，我们搜索所有 j > i 并评估交换的效果。 我们仅在概念上模拟交换：字符串在位置 i 和 j 处不同，因此我们从 i 开始仔细与 c 进行比较。 
5. 在所有有效的交换中，我们保留按字典顺序产生最小结果字符串的交换。 
6. 如果我们发现任何有效的交换，则在应用最佳交换后输出结果字符串。 否则输出“---”。 

### 为什么它有效

 正确性来自于字典顺序是在第一次不匹配时确定的。 任何有利的互换都必须提高 s 能够击败 c 的最早位置。 一旦我们确定了位置 i，改进以后的位置就无法弥补位置 i 的恶化。 因此，最佳交换始终是优化最早可能的索引的交换，并且其中最小化该索引处的结果字符。 

这将搜索空间从所有对减少到仅影响前缀关键位置的那些交换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s, c = input().split()
    n = len(s)

    # already good
    if s < c:
        print(s)
        return

    best = None  # (result_string)

    s_list = list(s)

    for i in range(n):
        for j in range(i + 1, n):
            if s_list[i] == s_list[j]:
                continue

            t = s_list[:]
            t[i], t[j] = t[j], t[i]
            cand = ''.join(t)

            if cand < c:
                if best is None or cand < best:
                    best = cand

    if best is None:
        print("---")
    else:
        print(best)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```该实现直接遵循暴力破解思想，但依赖于总长度约束（sum ≤ 5000），这使得每次测试的 O(n²) 在实践中是可以接受的。 当 s < c 时提前退出很重要，因为它可以避免不必要的搜索，并确保我们不会意外地恶化已经优化的有效字符串。 

嵌套循环会尝试所有交换，并且我们显式地为每个候选者构建一个新字符串。 由于 n 总体上很小，因此这仍然在限制范围内。 

## 工作示例

 ### 示例 1

 输入：s =“AZAMON”，c =“APPLE”

 我们首先检查是否 s < c。 第一个不同的字符是“A”与“A”，然后是“Z”与“P”，并且由于 Z > P，因此 s 并不小于。 

我们尝试交换：

 | 我| j | 交换的字符串 | 与 c 比较 | 有效 |
 | ---| ---| ---| ---| ---|
 | 0 | 3 | 亚马逊 | 亚马逊 < 苹果 | 是的 |

 我们发现“AMAZON”是有效的并且是最佳候选，因此我们输出它。 

这证实了一次交换可以将较小的字符移到字符串的前面，从而修复第一个不匹配的问题。 

### 示例 2

 输入：s =“苹果”，c =“香蕉”

 我们检查 s < c。 第一个字符 'A' < 'B'，因此 s 已经有效。 

我们立即输出“APPLE”。 

这显示了不需要交换的情况，任何修改只会有使字符串变得更糟的风险。

 ## 边缘情况

 用于输入`s = "ABC", c = "ABD"`，算法首先检查`s < c`并立即输出`ABC`。 像交换 A 和 C 这样的交换会产生`CBA`，这更糟糕并且被正确忽略。 

用于输入`s = "CBA", c = "ABC"`，没有交换可以使第一个字符小于“A”。 暴力搜索找不到有效的候选者并输出`---`。 这证实了如果 s 中的最小可能第一个字符已经太大，则无论以后如何重新排列，该问题都是不可能的。
