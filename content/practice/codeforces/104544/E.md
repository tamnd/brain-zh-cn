 ## 解决方案
 ## 问题理解

 我们有两个长度的数组$n$。 第一个数组表示位置的当前“值”，第二个数组表示每个位置如何随时间演变。 我们还有一个运行的进程$k$秒。 每一秒，我们选择一个索引$pos$，获得该索引的当前值，然后将该所选值减少固定量，而所有其他索引部分恢复到其原始起始值。 

因此，系统的行为就像一个资源池，您从一个位置收获的每一步，该位置对于未来的使用都会变得不那么有价值，而所有其他位置都会向上漂移到其初始状态，但不能超过它。 

目标是选择一个序列$k$最大化总收获量的指数。 

限制条件很大：$n$可以达到$2 \cdot 10^5$跨测试和$k$可以大到$10^9$。 这立即排除了随着时间的推移进行的任何模拟。 即使对于单个测试用例，任何显式处理每秒的解决方案都将失败。 唯一可行的方法必须将这一过程简化为每个职位或每个国家“周期”的贡献总额。 

一个关键的困难来自于元素之间的耦合。 选择一个指数会降低其未来价值，但会增加其他指数的上限，这意味着每个指数的决策并不独立。 

当假设每个指数独立地表现为一个简单的递减算术级数时，就会出现一个幼稚的错误。 这会失败，因为值可以通过其他操作恢复。 另一种故障模式来自于假设当前最大值的贪婪选择是最优的，这种假设会失败，因为过于频繁地选择最大值会降低其未来的可用性，而不考虑其他恢复的速度。 

## 方法

 暴力解释模拟每一秒：选择最佳的当前位置，更新所有值，重复。 这是正确的，但在计算上是不可行的。 每一步都需要$O(n)$更新，我们这样做$k$次，给予$O(nk)$，这取决于$2 \cdot 10^{14}$最坏情况下的操作。 

关键的观察结果是，每个元素的演化仅取决于它被选择的次数，而不是选择的确切顺序。 索引的总贡献取决于它的使用次数，因为每次使用它的值都会线性减少$b_i$，而其他更新仅确保它永远不会超过其初始值。 这将时间分解为每个元素的使用计数。 

我们不是模拟时间，而是将问题视为分布$k$在指数中进行选择。 如果选择一个索引$x$次，它的贡献变成一个固定的算术和，具体取决于$a_i, b_i$，并且它的未来重置确保在一段时间没有被选择后，它返回到其初始值。 

因此，每个索引在重复选取时都有一个“值序列”：$a_i, a_i - b_i, a_i - 2b_i, \dots$。 问题变成了选择$k$所有这些序列中的元素总数，但有每个索引的序列可以按顺序获取的约束。 

这转化为所有指数中最佳可用下一个收益的全局选择，其中每个指数贡献递减的边际收益。 我们维护下一个可能收益的结构，并重复取最大的收益，更新该指数的下一个值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟|$O(nk)$|$O(n)$| 太慢了|
 | Priority-based marginal selection |$O(k \log n)$|$O(n)$| 最坏情况下太慢|
 | 优化批量推理/阈值 |$O(n \log n)$|$O(n)$| 已接受 |

 缺少的见解是我们实际上不需要处理$k$单独当$k$是巨大的。 相反，我们利用单调性：每个索引都会产生一个递减的算术序列，因此我们可以计算有多少项超过全局阈值和聚合贡献。 

## 算法演练

 1. 对于每个索引$i$，想象一下反复单独选择它。 其收益呈递减序列$a_i, a_i - b_i, a_i - 2b_i, \dots$。 最后一个正项由何时确定$a_i - x b_i > 0$， 所以$x$大致是$a_i / b_i$。 这告诉我们每个索引可以生成多少有用的选择。 
2. 我们将每个指数转换为潜在收益列表。 我们不存储所有值，而是使用算术级数结构对它们进行推理。 指数的总贡献$x$选择是：$$x a_i - b_i \frac{x(x-1)}{2}.$$3. 因为我们必须准确地选择$k$总体运营，全球问题变成分布式$k$选择不同的指数来最大化这些凹函数的总和。 
4. 采取的边际收益$j$从索引中选择第 - 个$i$是$a_i - (j-1)b_i$。 这些边际收益形成每个指数的递减序列，因此在全球范围内我们希望顶部$k$所有这些序列的值。 
5. 我们不是显式生成所有序列，而是二分搜索阈值$T$，表示所选增益中最小的增益$k$运营。 
6. 对于固定$T$，每个索引贡献其算术级数中至少为的所有项$T$。 我们可以使用以下方法计算存在多少个这样的术语：$$cnt_i = \max\left(0, \left\lfloor \frac{a_i - T}{b_i} \right\rfloor + 1 \right).$$7. 我们总结所有$cnt_i$。 如果总数至少为$k$， 临界点$T$太低了，所以我们增加它。 否则，我们会减少它。 
8. 找到阈值后，我们计算严格高于该阈值的所有值的总和，然后通过精确取值进行调整$k$最大的贡献。 

### 为什么它有效

 每个操作独立地贡献为从一组递减序列中提取的边际增益。 由于序列是单调的，因此选择顶部$k$来自并集的元素相当于选择截止点以上的所有元素加上边界处的部分切片。 二分搜索唯一地识别该截止点，算术级数公式允许我们计算计数和总和，而无需显式枚举。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        def count_ge(x):
            total = 0
            for i in range(n):
                if a[i] < x:
                    continue
                total += (a[i] - x) // b[i] + 1
            return total

        def sum_ge(x):
            total = 0
            for i in range(n):
                if a[i] < x:
                    continue
                cnt = (a[i] - x) // b[i] + 1
                last = a[i] - (cnt - 1) * b[i]
                total += cnt * (a[i] + last) // 2
            return total

        lo, hi = 1, max(a)
        while lo <= hi:
            mid = (lo + hi) // 2
            if count_ge(mid) >= k:
                lo = mid + 1
            else:
                hi = mid - 1

        T = hi
        res = sum_ge(T)

        used = count_ge(T)
        res -= (used - k) * T

        print(res)

if __name__ == "__main__":
    solve()
```该代码首先定义辅助函数来对高于阈值的贡献进行计数和求和。 二分查找找到最大阈值，使得至少$k$值可用。 然后，我们计算高于或等于该阈值的所有值的总和，并通过删除边界级别的额外元素来纠正过度计数。 

一个微妙的点是我们依赖于整数算术级数和； 未能使用正确的最后一项公式会导致总计不正确。 另一个重要的细节是计数后的调整步骤，这可以确保准确$k$操作都包含在内。

 ## 边缘情况

 一个关键的边缘情况是当所有$a_i$相对于较小$k$，这意味着我们为每个索引消耗完整的序列。 该算法通过将阈值设置得非常低来处理此问题，导致计算所有边际收益，然后精确截断$k$。 

当一个索引以非常大的索引占主导地位时，会出现另一种边缘情况$a_i$和小$b_i$。 二分搜索正确地设置了一个高阈值，以便仅选择该索引的早期较大收益，而其他索引则不会贡献高于截止值的任何贡献。 

第三种情况是当$b_i$足够大，每个索引最多贡献一个或两个值。 计数公式仍然有效，因为整数除法立即压缩了序列长度，并且阈值逻辑自然只选择有效的初始增益。
