 ## 解决方案
 ## 问题理解

 我们被要求决定在两个约束条件下，Yazan 点两道菜（每位朋友一份）的价格有多便宜。 

第一道菜有成本`a`并且必须至少是`x`。 第二道菜有成本`b`并且与总账单相关：它必须至少`y%`的综合成本`a + b`。 

所以结构是圆形的。 的价值`b`取决于总数，但总数取决于`b`。 目标是选择整数`a`和`b`满足这两个条件，同时最小化`a + b`。 

输入给出多个独立的测试用例，每个都有边界`x`和`y`。 对于每个测试用例，我们必须输出尽可能小的总成本或`-1`如果不存在有效的对。 

关键的困难是自我参照约束`b`。 天真的尝试会尝试所有对`(a, b)`达到某个界限，但任一变量都没有明显的有限上限。 然而，由于这两个约束只会随着价值的增长而增加成本，因此任何最佳解决方案都将处于最小的可行值，这强烈表明我们不应该探索大范围。 

出现微妙的边缘情况时`y = 100`。 在这种情况下，第二个约束变为`b ≥ a + b`，这迫使`0 ≥ a`，不可能，因为`a ≥ x ≥ 1`。 所以每个测试用例`y = 100`立即是不可行的。 

另一个潜在的陷阱是将百分比约束错误地视为`b ≥ (y/100) * a`，它忽略了百分比是总数，而不仅仅是第一道菜。 

## 方法

 暴力方法会尝试所有整数对`(a, b)`直到某个最大界限，检查两个约束是否成立并跟踪最小总和。 虽然正确，但这在计算上并没有明确定义，因为没有自然的上限`a`和`b`，即使我们强加一个像 10^5 这样的值，在 O(N^2) 下也太慢了。 

关键的观察结果是可以重写第二个约束以消除循环依赖。 开始于：`b ≥ y/100 * (a + b)`我们重新排列：`100b ≥ y(a + b)`

`100b ≥ ya + yb`

`(100 - y)b ≥ ya`如果`y < 100`，这变成：`b ≥ (y * a) / (100 - y)`所以对于一个固定的`a`, 最小有效值`b`是直接确定的。 这完全消除了依赖循环。 

现在问题变得最小化：`a + b(a) = a + ceil(y * a / (100 - y))`由于这两项都线性增长`a`，总和单调递增`a`增加。 因此，最优解总是使用尽可能小的`a`，即`a = x`。 

这将整个问题简化为直接计算，特殊情况除外`y = 100`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解 (a, b) | O(N²) 或无界 | O(1) | O(1) | 太慢/未定义|
 | 配方减少 | 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 ### 最佳方法

 1. 检查是否`y == 100`。 如果有则立即输出`-1`。 这是因为约束力`b ≥ a + b`，这对于任何正数都是不可能的`a`。 
2. 否则计算最小有效值`a`，这始终是`a = x`。 增加`a`只会增加总成本和所需的成本`b`，因此没有更大的选择可以改善答案。 
3. 将约束重写为直接下界`b`：`b ≥ (y * a) / (100 - y)`4. 计算最小整数`b`使用上限除法来满足这个界限。 
5、输出`a + b`。 

### 为什么它有效

 该转换消除了之间的依赖循环`a`,`b`，以及总和。 对于任何固定的`a`，约束唯一确定最小可行`b`。 既然两者`a`和`b(a)`是非递减函数`a`，目标函数`a + b(a)`也是非递减的，所以它的最小值必须出现在最小的可行值处`a`。 这保证了限制注意力`a = x`不排除任何最优解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    x, y = map(int, input().split())
    
    if y == 100:
        print(-1)
        continue
    
    a = x
    numerator = y * a
    denominator = 100 - y
    
    b = (numerator + denominator - 1) // denominator
    print(a + b)
```代码直接遵循推导公式。 唯一的分支是`y == 100`case，它处理不可能性条件。 

吊顶划分`(numerator + denominator - 1) // denominator`很关键； 使用浮点运算会带来精度错误的风险，特别是因为约束很严格并且需要精确的整数正确性。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        x, y = map(int, input().split())
        if y == 100:
            out.append("-1")
            continue
        a = x
        b = (y * a + (100 - y) - 1) // (100 - y)
        out.append(str(a + b))
    return "\n".join(out)

 ## 边缘情况

 ###案例`y = 100`输入：```
x = 5, y = 100
```约束变为：`b ≥ a + b`减法`b`给出`0 ≥ a`，这与`a ≥ 5`。 算法立即返回`-1`在任何计算之前。 

＃＃＃ 小的`y`价值观

 输入：```
x = 1, y = 1
```这里的百分比约束非常弱。 该算法计算：`b = ceil(1 / 99) = 1`，所以总计是`2`。 最小的`a`选择仍然是最优的，因为增加`a`只会使分子和总数恶化。 

＃＃＃ 大的`x`输入：```
x = 100, y = 50
```算法修正`a = 100`，然后计算`b = ceil(5000/50) = 100`，给出总计`200`。 任何更大的`a`只会按比例增加两个值，从而确认边界选择始终是最佳的。
