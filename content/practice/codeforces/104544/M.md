 ## 解决方案
 ## 问题理解

 我们得到了几个测试用例。 每个测试用例中都有$n$小队和$k$员工类型。 每个小队都被编码为长度的位掩码$k$，其中位$j$指示该小队当前是否包含以下类型的员工$j$。 

我们可以独立修改每个小队，每个小队只能修改一次。 修改包括从该班组中删除任何现有员工类型或向该班组添加缺少的员工类型。 从概念上讲，每个小队最终都会将其原始位的某些子集向任意方向翻转，但每个小队只有一次操作。 

完成所有修改后，我们评估公司得分。 A型$i$贡献$2^i$当且仅当每个小队都包含该类型时才得分。 否则，该类型的贡献为零。 

因此，目标是为每个小队选择一个允许的修改，以便“普遍存在”的位位置的数量在二的幂的加权和方面最大化。 

限制条件很严格$n$跨测试用例，最多$2 \cdot 10^5$， 尽管$k \le 30$。 这立即表明任何解决方案最多必须是线性或接近线性的$n$每个测试用例，以及任何二次$n$或指数$k$不会扩展。 

一个微妙的边缘情况来自这样一个事实：每个小队必须只修改一次。 这排除了简单地取所有位掩码的交集的简单想法：我们不是使用静态集，而是使用可以在有限的灵活性下进行局部调整的集。 

另一个陷阱是假设每个位都有独立的优化。 一种简单的方法可能会尝试单独决定每个位，但对小队的操作会同时影响多个位，因此可行性约束是耦合的。 

## 方法

 暴力的观点会考虑每个小队并枚举所有可能的单一操作，然后尝试跨小队的所有组合。 每个小队最多有$k$可能的火灾行动和$k$可能的雇佣操作，所以大致$O(k)$每个小队的选择。 这导致$O(k^n)$全局配置，即使是小规模的配置也是不可能的$n$。 

更结构化的暴力可能会尝试猜测最终的普遍存在的位集$S$。 一次$S$是固定的，必须调整每个小队，使其包含$S$经过一次操作后。 问题是每个小队是否可以兼容$S$，以及这种可行性对于每个小队是否独立成立。 

关键的洞察力是颠倒视角。 我们不是首先决定操作，而是修复候选位$i$并问：我们能否确保每个小队最终都包含 bit$i$一次手术后？ 如果一个小队已经有位$i$，没关系。 如果不是，我们必须使用它的单个操作来加位$i$。 然而，该操作仅更改一个小队，并可能影响该小队中的其他位。 这表明对于固定位$i$，唯一的障碍是球队是否有能力“负担得起”增加$i$不违反某些隐式一致性要求。 

关键的结构观察是每个小队都可以独立调整，唯一真正的限制是我们不能任意地将多个缺失位同时强行放入同一个小队中。 由于每个小队只进行一次行动，因此缺乏位的小队$i$必须将其运营“花费”在$i$，并且不能同时修复其他候选全局所需类型的其他缺失位。 

这导致对每一位进行贪婪的可行性测试：对于每一位$i$，我们计算有多少小队已经包含了它。 剩下的小队必须可以通过一次操作来修复，该操作引入了$i$。 由于操作可以添加或删除单个位，但我们只关心确保存在$i$，我们总是可以使用“添加$i$”对于任何缺乏它的小队。因此，可行性降低为这样一个事实：每个小队都可以包含$i$至多一次操作，这始终是正确的。 

因此，真正的耦合不是每个比特单独的可行性，而是多个比特是否可以同时执行。 如果我们尝试强制执行一组$S$，然后在任何丢失多个位的小队中$S$，我们只有一次操作来修复它们，所以我们必须确保每个小队最多缺失一位$S$。 这才是真正的限制。 

因此对于候选集$S$，每个小队必须至少包含$|S| - 1$位来自$S$。 这将问题转化为从最高权重到最低权重贪婪地选择位，从而保持可行性。 

我们处理来自$k-1$下降到$0$。 我们尝试包含位$i$如果仍然可以使所有小队包含所有选定的位，同时遵守“每个小队最多丢失一个位”约束，则可以将其纳入全局答案。 我们跟踪每个小队目前缺少多少选定的位。 如果任何小队超过一个缺失的选定位，我们就无法包含该位。

 | --- | --- | --- | --- |
 | 暴力破解分配|$O(k^n)$|$O(nk)$| 太慢了 |
 | 具有可行性跟踪的贪婪位选择 |$O(nk)$|$O(n)$| 已接受 |

 ## 算法演练

 我们维护一组全局选定位，并为每个小队跟踪当前不包含的这些选定位中有多少。 

1.初始化一个数组`miss[i] = 0`对于每个小队，表示该小队中缺少多少个选定的位。 
2. 迭代位位置$k-1$下降到$0$。 我们首先处理较高位，因为包含它们对最终答案贡献更大。 
3. 对于候选位$i$，计算它将如何影响每个小队。 如果小队当前没有位$i$，然后添加$i$将增加其相对于所选集合的缺失计数。 
4. 临时检查添加该位是否保留每个`miss[j] ≤ 1`。 如果任何小队有两个或更多缺失的选定位，那么包含该位是不可能的，我们会跳过它。 
5. 如果可行，我们将永久包含位$i$并更新`miss`因此。 
6. 处理完所有位后，将答案计算为$2^i$覆盖所有选定的位。 

关键的推理步骤在于我们如何解释操作：全局选择一个位会强制每个小队在一次本地调整后包含它，并且该单次调整只能“修复”每个小队一个丢失的选定位。 

### 为什么它有效

 该算法对于当前选择的位集保持不变$S$，每个小队最多缺失一位$S$。 这符合每个小队只能执行一项修改的操作约束，因此它最多可以修复相对于全局需求的一个缺陷。 当我们考虑添加一个新位时，只有当这个不变量仍然成立时，我们才会接受它。 由于我们按降序处理位，因此我们在保留可行性的同时，按字典顺序最大化位权重的贡献。 这确保了所选择的集合在约束下是最大的，这直接对应于最优效率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        miss = [0] * n
        chosen = 0

        # try bits from high to low
        for b in range(k - 1, -1, -1):
            can = True

            for i in range(n):
                has = (a[i] >> b) & 1
                if not has:
                    if miss[i] + 1 > 1:
                        can = False
                        break

            if not can:
                continue

            # apply bit
            chosen |= (1 << b)
            for i in range(n):
                if ((a[i] >> b) & 1) == 0:
                    miss[i] += 1

        ans = 0
        for b in range(k):
            if (chosen >> b) & 1:
                ans += (1 << b)

        print(ans)

if __name__ == "__main__":
    solve()
```实现直接遵循贪心构造。 这`miss`array 是中心状态：它测量每个小队当前缺少多少个选定位。 可行性检查可确保任何小队都不会超过一个缺失的选定位，因为这将导致无法通过单次操作进行修复。 

贪婪循环从高到低处理位，确保一旦一个位被拒绝，就永远不会重新考虑，这符合最大化二进制加权和的最优性要求。

 ## 边缘情况

 当发生最小情况时$n = 1$。 在这种情况下，每一点总是可行的，因为一个小队在经过一次允许的修改后总是可以满足所有要求。 该算法将贪婪地包括从高到低的所有位，并且`miss`永远不会超过 1，因为只有一支球队。 输出变成所有的总和$2^i$，与一个小队不施加全局限制的事实相匹配。 

当小队几乎不相交时，就会出现相反的情况。 例如，如果每个小队仅包含一个唯一位，则选择多个位会强制同一小队中存在多个缺失计数，从而提前违反约束。 该算法正确地停止在不会使任何小队过载的最高位，因为`miss`在尝试包含另一位时将立即超过 1。 

这两个极端表明，当约束不相关和约束最严格时，算法都能正确运行。
