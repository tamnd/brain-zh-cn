 ## 解决方案
 ## 问题理解

 我们得到一个整数数组和一个以非常结构化的方式更改数组的特殊操作。 每次应用该操作时，我们都会选择当前最小值的一次出现，将其删除，然后从每个剩余元素中减去相同的值。 这会将数组缩小一个元素，同时根据删除的最小值向上或向下移动剩余值。 

我们的目标不是盲目地模拟这些操作，而是决定我们应该应用它们多少次，以便最终的数组在某个中间阶段具有尽可能大的最小元素。 我们可以随时停止，包括在进行任何操作之前。 

这些约束足够大，任何重复模拟删除和完整数组更新的方法都会太慢。 每个操作都可能涉及所有剩余元素，因此当测试用例的总大小达到 2·10^5 时，即使是二次或接近二次的策略也会失败。 

当数组只有一个元素时，会出现一种微妙的边缘情况。 由于此处禁止操作，因此即使结果为负，答案也被迫为原始值。 另一个棘手的情况是所有元素都相同。 每个操作都会删除一个元素并将其余元素移至零，因此答案在该值上变得稳定，但天真的模拟可能会过度考虑删除的顺序，即使它并不重要。 

## 方法

 直接模拟将重复扫描数组以查找其最小值，将其删除，然后从所有剩余元素中减去它。 经过 k 次操作后，数组的大小为 n−k，每一步的成本为 O(n)，在最坏的情况下，每个测试用例的成本为 O(n²)。 当总 n 达到 2·10^5 时，这太慢了。 

关键的观察结果是，该操作仅取决于元素按值的排序，而不取决于它们的位置或身份。 每一步都会消除当前的全局最小值。 这意味着该过程本质上是按升序剥离元素，同时不断移动剩余值，以便每次操作后当前最小值变为零。 

与其模拟，我们可以逆向思考：对数组进行排序后，我们考虑如果将较小的元素一一“抵消”，最小值会如何演变。 最佳停止点对应于选择要完全提取的排序数组的前缀。 剩余的元素已通过减去所有删除的最小值而全部移动。 

如果我们对数组进行排序，那么在删除前 i 个最小元素后停止的任何阶段，通过减去那些删除的最小贡献的总和，可以有效地转换剩余元素。 因此，剩余集合的最小值由尚未删除的最小原始元素减去先前删除的累积偏移确定。 

这种结构允许我们通过跟踪运行的减法偏移量，在一次遍历排序数组的过程中计算候选答案。

 | ---| ---| ---| ---|
 | 暴力模拟| O(n²) | O(n) | 太慢了 |
 | 排序+前缀推理| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对数组进行非降序排序。 这会将所有未来的删除按照它们发生的确切顺序对齐，因为该操作总是删除当前的最小值。 
2. 维护运行变量`shift`，最初为零。 这表示由于先前删除的最小值而从所有剩余元素中减去的总量。 
3. 从最小到最大迭代排序后的数组。 在位置 i，治疗`a[i] - shift`作为当前元素经过所有先前操作后的有效值。 
4. 在每一步，计算一个候选答案等于`a[i] - shift`。 如果我们在处理到这一点后停止，这表示剩余元素中的最小值。 
5. 更新`shift`通过添加`a[i]`。 这反映出，如果我们至少删除该元素，则所有剩余元素将在未来的操作中减少该值。 
6. 跟踪所有候选点的最大值，因为我们希望最大化所有可能停止点中的最终最小值。 

### 为什么它有效

 排序后，每次操作都会删除尚未处理的剩余原始值中最小的。 每个移除的元素都将其值精确地贡献给应用于所有后续元素的累积减法。 这使得任何未删除元素的有效值等于其原始值减去所有先前删除元素的总和。 因此，任何停止点的最小值始终由排序顺序中的第一个未处理元素确定，并通过累积移位进行调整，这正是算法评估的内容。 

不存在改变此结构的重新排列选择，因为删除当前数组的任何最小元素必须对应于在重新索引后删除下一个最小的原始元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 1:
        print(a[0])
        continue
    
    a.sort()
    
    shift = 0
    ans = -10**18
    
    for i in range(n):
        ans = max(ans, a[i] - shift)
        shift += a[i]
    
    print(ans)
```该解决方案首先单独处理单元素情况，因为那里不允许任何操作。 排序至关重要，因为它将强制删除的顺序与递增的值对齐。 

变量`shift`累积由于先前删除而应用于剩余元素的总减法。 在每个索引处，我们评估如果我们在那里停止该过程，当前最小剩余值会变成什么。 答案是该值的最大值。 

一个常见的陷阱是忘记在评估当前元素后必须更新移位。 颠倒此顺序会错误地将减法应用于当前候选项，并使所有结果向下移动。

 ## 边缘情况

 单元素数组直接强制输出为该元素，因为不允许进行任何操作。 在这种情况下，算法显式地提前返回，避免不必要的排序或移位。 

对于相同值的数组，例如`[x, x, x]`，排序不起作用，每个候选者都变成`x - kx`增加 k，但最大值出现在第一步，产生 x。 运行移位逻辑自然地捕获了这一点，因为每个候选值在应用其相应的减法之前都会被评估。 

对于先有大负值后有正值的数组，这种移位会提前积累负质量，从而有效地增加后面的元素。 排序过程确保无需模拟破坏性更新即可解决这一问题，因为每个状态仅取决于排序数组的前缀和。
