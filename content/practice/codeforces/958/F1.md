 ## 解决方案
 ## 问题理解

 我们得到一排绝地武士，每个绝地武士在阵列中占据一个固定位置，并且每个绝地武士都有几种可能的光剑颜色之一。 除此之外，我们还得到了一个目标规格，告诉我们必须选择每种颜色的绝地武士数量。 

任务是确定阵容中是否存在连续的部分，这样，如果我们只查看该部分内的 Jedi，每种颜色出现的次数与所需的计数完全匹配。 

因此，输入本质上是一个长度为 n 且值在 1 到 m 范围内的数组，加上另一个描述目标频率向量的长度为 m 的数组。 输出是一个简单的可行性检查：是否有任何子阵列具有完全相同的频率分布。 

约束很小，n 最大为 100。这立即消除了对复杂数据结构或渐近最优预处理的任何需要。 即使是 O(n3) 的解决方案也是可接受的，并且 O(n2) 或 O(n2 log n) 的速度也相当快。 

一个微妙但重要的一点是，我们并不是在寻找元素的任何排列或选择，而是在寻找连续的片段。 这种限制使得前缀频率技术变得有用。 

一个常见的陷阱是忘记多个片段的总长度可能与目标总长度相同，但组成仍然不同。 例如，如果 m = 2 并且目标为 {1, 2}，则像 [1, 1, 2] 这样的段具有正确的长度但分布错误，而 [1, 2, 2] 也会失败，即使它符合关于平衡计数的一些部分直觉。 我们必须精确匹配所有颜色计数，而不仅仅是总长度。 

另一种边缘情况是某些颜色的目标为零。 有效的段必须包含这些颜色的出现次数为零，这意味着它必须完全避免它们。 

## 方法

 最直接的想法是检查每个可能的子数组。 对于每个起始索引，我们扩展结束索引并维护当前窗口内每种颜色的计数。 每当计数与目标向量匹配时，我们就可以立即返回 YES。 

这是可行的，因为只有 O(n²) 个子数组，并且增量地维护频率计数使得每个扩展步骤的每次检查都为 O(1)。 因此，总工作量约为 n² 次更新。 

如果我们以不同的方式描述它，暴力破解仍然会变得更加清晰：对于每个左端点，我们重置频率数组，然后在更新计数时扩展右端点。 每次扩展都会花费恒定的时间，但我们对每对端点都这样做。 

关键的观察是，我们不需要任何高级优化，例如散列或前缀和减法技巧，因为约束已经允许直接检查所有间隔。 颜色上的前缀和是另一个有效的观点：我们可以预先计算前缀频率数组，以便每个分段查询变为 O(m)，并且由于 m ≤ n ≤ 100，即使这样仍然可以接受。 

因此，最优解决方案本质上与增量记账的暴力破解相同。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（重新计算每个段的计数）| O(n3) | O(米) | 太慢了 |
 | 滑动窗口/增量频率| O(n² · m) 或 O(n²) | O(米) | 已接受 |

 ## 算法演练

 1.存储目标频率数组`k`，它定义了我们必须匹配的确切组合。 这成为所有比较的参考向量。 
2. 迭代所有可能的左端点`l`的一个段。 每一个选择`l`定义一个从空段开始的新频率计数器。 
3.初始化频率数组`cnt`尺寸的`m`电流为零`l`。 这表示当前子数组中的计数`[l, r]`。 
4. 延伸右端点`r`从`l`到`n - 1`, 更新`cnt[color[r]]`每一步加一。 这种增量更新避免了从头开始重新计算计数。 
5、每次扩展后，进行比较`cnt`与目标数组`k`。 如果所有颜色都相同，则立即返回 YES。 这项检查是正确的，因为`cnt`始终准确地表示子数组`[l, r]`。 
6. 如果没有配对`(l, r)`所有迭代后产生匹配，返回 NO。 

### 为什么它有效

 在每个固定的左端点`l`，算法枚举每个可能的右端点`r ≥ l`，并且对于每一对，它计算子阵列的精确频率向量`[l, r]`。 由于每个可能的连续段在此枚举中仅出现一次，因此将测试任何有效的解决方案。 频率比较在所有m个维度上都是完全相等的，因此不可以通过任何错误的段，也不可以错过任何正确的段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    k = list(map(int, input().split()))

    for l in range(n):
        cnt = [0] * m
        for r in range(l, n):
            cnt[a[r] - 1] += 1
            if cnt == k:
                print("YES")
                return

    print("NO")

if __name__ == "__main__":
    solve()
```外循环固定段的左边界。 对于每个这样的边界，都会创建一个新的频率数组，以便计数完全对应于从`l`。 

内部循环一次一步地扩展右边界，仅更新频率数组中的一项。 这使得每次扩展的时间复杂度为 O(1)，而不是重新计算整个段的计数。 

比较`cnt == k`是安全的，因为两者都是大小为 m 的固定长度列表，并且 Python 按元素进行比较。 由于 m ≤ 100，这种比较仍然有效。

 ## 边缘情况

 一种边缘情况是所需的段是整个数组。 例如：```
n = 4, a = [1,2,3,1], k = [1,1,1]
```算法最终达到`l = 0, r = 3`, 构建`cnt = (1,1,1)`，并正确返回 YES。 

另一种情况是有效段位于最后。 例如：```
a = [2,2,1], k = [1,2]
```仅子数组`[2,1]`作品，发生在`(l=1, r=2)`。 外循环确保`l=1`到达，内循环在扩展到时发现匹配`r=2`。 

最后一个微妙的情况是不允许出现任何颜色。 如果`k[i] = 0`对于某些颜色，算法自然会拒绝包含该颜色的任何段，因为一旦该颜色增加，频率向量比较就会失败。
