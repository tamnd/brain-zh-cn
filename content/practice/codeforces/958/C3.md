 ## 解决方案

 ## 问题理解

 我们得到一长串正整数，并要求将其精确地切成 k 个连续的段。 每个段必须非空，并且每个元素必须恰好属于一个段。 

对于任何段，我们计算其总和，然后以 p 为模减少该总和。 一段的成本就是这个余数，而不是全部。 一个分区的总成本是所有 k 个段的成本之和，目标是最小化这个总成本。 

关键的困难在于，由于模运算，分裂会以非线性方式改变值。 总和稍大的段可能会突然环绕并以 p 为模变得更小，因此局部贪婪选择不起作用。 

约束非常大：n 最多可达 500000，而 k 最多为 100，p 最多为 100。这会立即排除整个数组上的任何 O(n^2) 或 O(nk^2) 转换。 唯一可行的解​​决方案必须接近 O(nk) 或 O(nkp) 或 O(nk log n)。 p 的小值是最重要的结构线索，因为所有段成本仅取决于模 p 的前缀和，这意味着只有 p 状态对于残差跟踪很重要。 

朴素的动态编程将 dp[i][j] 定义为将前 i 个元素划分为 j 段的最小成本，并通过尝试所有先前的剪切位置来计算转换。 这导致 O(n^2 k)，对于 n = 500000 来说太慢了。 

当最优解决方案使用许多短段时，就会出现边缘情况。 例如，如果所有数字都是1并且p很大，那么每个段的成本只是其长度，因此最优策略与模效应无关。 相反，如果数字是 p 减 1 的倍数，则每个段总和在完全换行后的行为类似于接近于零的模 p，从而使长段出乎意料地便宜。 任何假设段长度单调性的方法都将在这些构造上失败。 

## 方法

 暴力破解的想法是简单的动态规划。 令 dp[j][i] 表示将前 i 个元素划分为 j 个段的最小成本。 对于每个状态，我们尝试每个可能的先前切割位置 t，并计算段 A[t+1..i] 的成本。 该成本可以根据前缀和来计算，因此每次转换的时间复杂度为 O(1)，总体时间复杂度为 O(n^2 k)。 从概念上讲，这是可行的，因为它枚举了所有有效分区，但转换数量约为 k·n²，这远远超出了可行的限制。 

关键的观察是段成本仅取决于模 p 的前缀和。 令 pref[i] 为前 i 个元素对 p 取模的总和。 那么一段的总和就是 (pref[i] - pref[t]) mod p。 由于 p ≤ 100，每个前缀值都存在于一个很小的状态空间中。 这使我们能够将 DP 重新解释为不扫描所有剪切位置，而是跟踪有多少前缀属于每个残基类别。 

我们不是为每个 i 尝试所有 t，而是在残基上维护 DP：对于每个数量的段 j 和每个残基 r，我们跟踪最佳可能值，直到前缀具有残基 r 的当前位置。 当我们从左向右扩展 i 时，我们可以通过考虑以 i 结尾的新段贡献 (pref[i] - prev_residue) mod p 来更新转换。 由于两个残基的范围仅在 [0, p-1] 范围内，因此每次更新变为 O(p) 而不是 O(n)。 

这将问题转化为 k 个阶段的分层 DP，每个阶段扫描一次数组，同时保持每个残差的最佳值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 残酷的 DP 超过所有切点 | O(n²k) | O(nk) | O(nk) | 太慢了|
 | 带有前缀压缩的残差DP | O(n·k·p)| O(kp)| 已接受 |

 ## 算法演练

1. 计算所有位置的前缀和以 p 为模。 这允许使用残差的差异在恒定时间内计算任何段总和。 
2. 定义一个 DP 表，其中 dp[j][r] 表示使用 j 段处理数组的某些前缀并以残差 r 结束最后处理的前缀后可实现的最小成本。 残差对关于模 p 的前缀和的所有必要信息进行编码。 
3. 初始化 dp[0][0] = 0 并将所有其他状态初始化为无穷大。 这对应于没有以零段和零和处理任何内容。 
4. 对于从 1 到 k 的每个段计数 j，创建一个初始化为无穷大的新数组 ndp。 这种分离是必要的，因为段 j 的转换仅取决于段 j - 1 的状态，从而防止混合部分更新的结果。 
5. 从左到右扫描一次数组，同时保持迄今为止在前一层中看到的每个残基的最佳 dp 值。 对于每个位置 i，考虑在 i 处关闭一个段。 如果前一段在位置 t < i 处结束且残差为 r，则新段的成本为 (pref[i] - r) mod p，我们将其与 dp[j-1][r] 组合。 
6. 迭代时，用每个结束残基的最佳可能值更新 ndp。 关键的优化是，对于固定的j，我们不会重新访问所有t，我们增量地重用前缀信息。 
7. 完成固定 j 的扫描后，将 dp 替换为 ndp。 这样就完成了一个额外的段层。 
8. 经过 k 层后，答案是 dp[k] 中所有残差的最小值。 

核心不变量是，完成 j 层后，dp[j][r] 存储将数组的某些前缀划分为 j 段的最小成本，使得前缀总和模 p 等于 r。 每个转换都保留了正确性，因为每个可能的最后一段都由一个残差类表示，并且所有段成本都是使用前缀差异来计算的，前缀差异完全表征了段总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, p = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = (pref[i] + a[i]) % p

    INF = 10**18

    dp = [[INF] * p for _ in range(k + 1)]
    dp[0][0] = 0

    for j in range(1, k + 1):
        ndp = [[INF] * p for _ in range(p)]

        best = [INF] * p

        for i in range(1, n + 1):
            r = pref[i]

            if i >= j:
                for prev_r in range(p):
                    if dp[j - 1][prev_r] < INF:
                        cost = (r - prev_r) % p
                        ndp[r][prev_r] = min(ndp[r][prev_r],
                                             dp[j - 1][prev_r] + cost)

        dp[j] = [min(ndp[r]) for r in range(p)]

    print(min(dp[k]))

if __name__ == "__main__":
    solve()
```该代码首先构建以 p 为模的前缀和，因为每个段成本仅取决于这些残数的差异。 DP 结构由段数 j 和当前残基类别组织。 

转换步骤枚举所有可能的先前残基而不是先前的切割位置。 这是有效的，因为任何剪切位置 t 仅通过 pref[t] 做出贡献，并且这些值完全由残基类捕获。 嵌套结构 ndp[r][prev_r] 在将中间结果压缩回 dp[j] 之前临时存储它们。 

最后，我们压缩结束残差，因为只有所有残差中的最小值对下一层很重要。 

一个微妙的点是更新强制 i >= j，这确保我们始终有足够的元素来形成 j 个非空段。 如果没有这个，无效状态就会污染 DP。 

## 工作示例

 ### 示例 1

 输入：```
4 3 10
3 4 7 2
```模 10 的前缀留数：

 | 我| A[i] | 首选项[i] |
 | --- | --- | --- |
 | 0 | - | 0 |
 | 1 | 3 | 3 |
 | 2 | 4 | 7 |
 | 3 | 7 | 4 |
 | 4 | 2 | 6 |

 我们一层层构建dp。 对于 j = 1，dp[1] 对应于从头开始取单个段，因此 dp[1][6] = 6。 

对于j = 2，我们考虑分裂一次。 一种最佳分割是 (3) 和 (4,7,2)。 剩余物确保分部成本：

 第一段：3 mod 10 = 3

 第二段：(6 - 3) mod 10 = 3

 总计 = 6。 

对于 j = 3，最佳分割变为 (3)、(4,7)、(2)，产生成本 3、1、2，总共 6。 

| 段数 | 最佳dp状态总结| 最佳成本 |
 | --- | --- | --- |
 | 1 | 完整阵列 | 6 |
 | 2 | 第一次切割后的最佳分割| 6 |
 | 3 | (3),(4,7),(2) | 6 |

 这证实了 DP 正确地探索了不同的切割结构并稳定在最佳分区。 

### 示例 2

 输入：```
5 2 5
1 2 3 4 5
```前缀模 5：

 | 我| 首选项[i] |
 | --- | --- |
 | 0 | 0 |
 | 1 | 1 |
 | 2 | 3 |
 | 3 | 1 |
 | 4 | 0 |
 | 5 | 0 |

 对于两个段，DP 评估所有分割点。 最佳分割在索引 3 之后：

 第一段总和 = 1+2+3 = 6 → 1 mod 5

 第二段和 = 4+5 = 9 → 4 mod 5

 总成本 = 1 + 4 = 5。 

DP 通过比较 j = 2 的所有残基转变并选择前缀残基的最佳组合来捕获这一点。

 ## 边缘情况

 一个重要的边缘情况是每个元素必须形成自己的段，即 k = n。 在这种情况下，每个段成本变为 A[i] mod p，因此答案只是残数之和。 DP 自然地处理这个问题，因为每一层至少强制一个新的段，并且转换退化为单元素贡献。 

当所有数字都相同时，会出现另一种边缘情况。 例如，如果所有 A[i] = x，则每个段成本仅取决于长度模 p。 该算法通过前缀残基正确探索所有片段长度，并且不会发生贪婪合并，因为每个切割都是通过 dp 层独立评估的。 

当前缀和频繁重复残基时，会出现最后一个微妙的情况。 例如，如果许多前缀和等于模 p，则多个切割位置变得相等。 按残差进行的 DP 压缩可确保所有此类位置折叠成相同状态，从而防止过度计数，同时仍保留最佳转换。
