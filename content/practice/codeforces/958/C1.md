 ## 解决方案

 ## 问题理解

 我们得到一个整数数组和一个模值$p$。 任务是选择一个单一的剪切位置，将数组分割成两个连续的非空段。 对于每个段，我们计算其总和，并对其进行模减$p$，然后将两个结果相加。 目标是找到使总价值最大化的削减。 

形式上，如果我们在位置之后进行剪切$i$，答案就变成：$$(\text{sum of } A[1..i] \bmod p) + (\text{sum of } A[i+1..n] \bmod p)$$输出是所有有效切割位置可实现的最大值。 

这些约束足够严格，足以在阵列大小上强制采用线性或近线性解决方案。 和$n \le 100{,}000$， 任何$O(n^2)$直接尝试所有子数组计算的方法太慢。 甚至一个$O(n \log n)$解决方案是可以接受的，但没有必要； 前缀和的结构使得这个问题可以在线性时间内解决。 

一个微妙的陷阱来自于对模与分裂如何相互作用的误解。 例如，人们可能认为您需要为每个分割重新计算总和，但前缀总和使每个段总和为 O(1)。 

另一个常见的错误是假设两个部分都独立最大化。 这是不正确的，因为切割将它们耦合在一起：增加一侧的总和可能会减少另一侧的模结果。 

一个小的说明性边缘情况是：

 输入：```
3 5
4 4 4
```如果我们在第一个元素之后进行剪切：$4 \bmod 5 + 8 \bmod 5 = 4 + 3 = 7$。 

如果我们在第二个之后剪切：$8 \bmod 5 + 4 \bmod 5 = 3 + 4 = 7$。 

两者都是平等的，天真的贪婪选择可能会错误地认为一个方向更好。 

## 方法

 蛮力的想法很简单。 我们尝试每一个可能的分割点$i$。 对于每个分割，我们计算左段和右段的总和，应用模$p$，然后添加它们。 如果我们从头开始为每次切割重新计算分段总和，则每次评估成本$O(n)$，导致$O(n^2)$总操作。 和$n = 10^5$，这变成了$10^{10}$，这远远超出了时间限制。 

我们可以通过注意到所有段和都可以使用前缀和来表达来改进这一点。 如果我们预先计算一个前缀和数组，那么任何段和都是常数时间减法。 这将每次分割评估减少到$O(1)$，进行全面扫描$O(n)$。 

关键的结构观察是目标仅取决于前缀和及其补集。 一旦知道了总和，就可以立即根据左段和确定右段和，因此我们不需要重新计算前缀累积之外的任何内容。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了|
 | 前缀和扫描|$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们根据前缀和重写问题，以便可以立即评估每个分割。 

### 步骤

 1. 计算数组的总和。 这使我们能够将任何后缀总和表示为与总和的差值，从而避免重新计算。 
2. 当我们从左到右迭代数组时，构建一个运行前缀和。 
3. 对于每个位置$i$从$1$到$n-1$，将其视为切点。 
4. 在每次切割时，计算左和作为前缀和，直到$i$。 右边的和是总和减去这个前缀和。 
5. 应用模数$p$到左和右总和并将它们相加。 
6. 跟踪所有切割位置的最大值。 

我们只迭代到的原因$n-1$是两个部分都必须非空，因此最后一个元素之后的剪切无效。 

### 为什么它有效

 该算法是正确的，因为数组的每个有效分区恰好对应一个前缀边界。 对于每个边界，左右总和是唯一确定的，并且没有其他隐藏结构影响分数。 由于我们对每个可能的边界只评估一次，因此这些评估的最大值就是全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, p = map(int, input().split())
    a = list(map(int, input().split()))

    total = sum(a)
    prefix = 0
    best = 0

    for i in range(n - 1):
        prefix += a[i]
        left = prefix % p
        right = (total - prefix) % p
        best = max(best, left + right)

    print(best)

if __name__ == "__main__":
    solve()
```该解决方案依赖于前缀和的单遍累积。 总和计算一次，以便在恒定时间内导出每个正确的段。 循环停止于$n-1$确保分割的两边都保持非空。 模运算仅在评估时应用，而不是在累加期间应用，这避免了不正确的中间归约。

 ## 边缘情况

 一种边缘情况是所有元素都相同，这可以使多个分割同样最优。 对于输入：```
5 7
3 3 3 3 3
```前缀评估给出对称结果。 在每次切割时，算法一致地计算前缀 mod 和后缀 mod，并且不会跳过任何分割。 扫描过程中自然会出现最大值。 

另一种边缘情况是模数强烈影响一侧时。 为了：```
4 5
4 4 4 4
```前缀和增长很快，但每次切割都会以不同的方式减少模 5。 该算法仍然对每个边界进行一次评估，因此即使原始总和具有误导性，它也能捕获最佳分割。 

最终的边缘情况是最小的有效输入大小：```
2 5
1 2
```正好有一个分裂。 循环运行一次，计算前缀 = 1、后缀 = 2，然后返回$1 + 2 = 3$。 不需要特殊的外壳，因为循环范围自然地强制执行两个部分都非空的约束。
