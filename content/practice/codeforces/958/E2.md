 ## 问题理解

 当海蒂暂时离开超空间时，我们会得到严格递增的时间序列。 这些时刻是会议开始或结束的唯一有效端点。 海蒂必须精心组织$K$不相交的会议，其中每次会议都通过选择两个索引来定义$i < j$并分配间隔$[t_i, t_j]$。 任何两个会议在时间上都不可能重叠，甚至禁止在端点处进行接触，因此如果一个会议在$t_i$，其他会议不能开始或结束于$t_i$。 

Each meeting has a cost equal to its duration$t_j - t_i$，目标是配对$2K$选定的时间点进入$K$不重叠的间隔使得长度的总和最小化。 

关键结构是我们从排序数组中选择对，形成不相交的线段，并且我们想要最小可能的差异之和。 

限制条件很大：$N$最多可达 500000 并且$K$最多 5000。这立即排除了尝试所有配对或在所有端点上使用二次动态规划的任何解决方案。 甚至$O(NK)$取决于常量，可能处于临界状态，但通过仔细的转换通常是可以接受的。 任何涉及$O(N^2)$或者枚举所有区间匹配是不可能的。 

一个微妙的边缘情况来自“无共享端点”约束。 如果我们忘记了这一点，我们可能会尝试对相邻元素进行贪婪配对，但这并不总是有效，因为最佳配对可能会跳过元素。 另一个失败案例是假设我们应该总是配对$t_i$和$t_{i+1}$，它忽略全局结构：有时尽早配对远元素可以缩小未来的间隙。 

例如，考虑：```
K = 2
t = [1, 2, 100, 101, 102]
```贪婪的相邻配对给出$[1,2]$和$[100,101]$， 成本$1 + 1 = 2$。 这实际上是最佳的，但现在修改：```
t = [1, 10, 11, 12, 20, 21]
```相邻贪心给出$[1,10], [11,12], [20,21]$对于 K=3 给出成本$9+1+1=11$，但配对$[10,11], [12,20]$结构表明，贪婪通常并不安全，因为配对选择会影响剩余的间隙。 

正确的解决方案必须全局决定使用哪些点以及它们如何配对。 

## 方法

 暴力方法会尝试选择$2K$点来自$N$然后将它们进行最佳配对。 即使我们修复子集，按排序顺序将它们最佳配对也很简单，但选择子集本身是组合性的。 可供选择的方式数量$2K$点是$\binom{N}{2K}$，对于$N = 500000$。 即使对于中等$K$，这是不可能的。 

我们需要利用点已经排序且区间不能重叠的结构。 这表明了一种动态规划的解释：一旦我们决定配对，它就会将问题分成左右部分的独立子问题。 

一个关键的观察是，在最佳解决方案中，如果我们对选定的端点进行排序，则配对始终以某种结构化方式在连续选定的元素之间进行。 更重要的是，我们可以考虑从左到右构建解决方案，决定是开始一个新的间隔还是关闭一个间隔，同时跟踪我们已经形成了多少个间隔。 

这导致 DP 超过位置和已完成对的数量，其中转换比较跳过一个点与将其用作一对的端点。 然而，一个天真的$O(NK)$DP 仍然需要仔细优化，因为每次转换都取决于配对选择，而配对选择隐式要求选择先前不匹配的端点。 

关键的改进是将问题重新解释为选择$2K$点并按顺序贪婪地将它们配对，这减少了对该归纳结构中匹配对之间的距离求和的成本。 这使我们能够将 DP 转换为经典的“选择端点”优化，其中我们只需要考虑在开始下一对之前跳过多少个元素。 可以使用前缀结构和滚动 DP 有效地计算得到的递归。 

优化后的解决方案使用 DP，其中$dp[k][i]$代表形成的最低成本$k$使用第一个对$i$元素，并进行仔细的转换，要么跳过元素，要么以受控方式将其与先前选择的端点进行匹配。 通过优化，我们通过确保转换仅考虑按排序顺序的有效结构配对来减少冗余重新计算。

 | 暴力配对子集 | 指数| 指数| 太慢了|
 | 具有优化的端点DP | O(NK) | O(K) 或 O(NK) | 已接受 |

 ## 算法演练

 我们从左到右处理排序后的数组，并保持动态编程状态，决定如何准确地形成$k$不相交的对。 

1. 定义$dp[k][i]$作为形成的最低成本$k$使用第一个对$i$时间点。 这捕获了在前缀中选择端点的所有有效方法。 

排序至关重要，因为间隔不能交叉，因此任何有效的结构都必须遵守索引顺序。 
2.就位$i$，我们要么不使用$t_i$，或者我们使用它作为一对的右端点。 如果我们不使用它，我们将继承以前的值：$dp[k][i] = dp[k][i-1]$。 
3.如果我们决定使用$t_i$作为端点，我们必须将其与一些之前未使用的点配对$t_j$， 在哪里$j < i$。 成本贡献为$t_i - t_j$。 因此，我们尝试所有有效的先前$j$可以作为第二个端点$k$第-对。 
4.而不是显式地迭代所有$j$，我们维持最佳候选结构：当我们增加$i$，我们可以解释为我们正在保持最佳的“开放”端点状态，该状态代表迄今为止最佳的选择点。 这使我们能够计算每个状态的摊余常数时间的转换。 
5.我们迭代$k$从 1 到 K，并且对于每个位置，按递增顺序更新 DP$i$，确保转换仅依赖于前一层$k-1$。 
6.最终答案是$dp[K][N]$，代表从完整序列中选择所有对的最佳方式。 

### 为什么它有效

 关键的不变量是任何最优解决方案都可以被视为$2K$索引并按排序顺序将它们配对，其中每对对应于所选点的归纳子序列中的连续段。 由于始终可以在不增加成本的情况下消除交叉，因此我们可以假设最佳配对是非交叉的。 这保证了在从左到右处理时，一旦段关闭，我们就不需要重新考虑之前的配对决策。 因此，DP 完全捕获了所有最优结构，而不会丢失任何配置。

        # Instead of explicit O(NK^2), we do optimized transition:
        # We maintain auxiliary array per k using running minimum
        # for pairing contributions.

        # To keep clarity and correctness in standard CF solution,
        # we rebuild DP with correct O(NK) formulation.

    # Correct implementation below:

    dp = [[INF] * (N + 1) for _ in range(K + 1)]
    for i in range(N + 1):
        dp[0][i] = 0

    for k in range(1, K + 1):
        best = INF

```DP 是逐层构建的，其中每一层都代表再形成一对。 内部变量`best`存储当前对的左端点的最佳选择：它跟踪以下值的最小值$dp[k-1][j] - t[j]$，这使我们能够计算$t[i] - t[j]$每个位置的转换时间恒定。 跳过过渡保留不使用当前点的选项。 

关键的微妙之处在于`best`必须为每个重置$k$，因为每个附加对仅取决于先前的对数。 里面的减法`best`是将两个索引搜索转换为单个运行最小值的原因。

 ## 边缘情况

 当最佳配对需要跳过明显的相邻匹配时，就会出现一种边缘情况。 对于输入：```
K = 2
t = [1, 2, 10, 11, 12]
```一种天真的贪婪方法会将 (1,2) 和 (10,11) 配对，而 12 未使用，这是无效的，因为所有端点必须完全成对使用。 相反，DP 探索配对 (2,10) 或 (1,10) 式结构，以确保可行性。 

在执行过程中，k=1 的 DP 很快就识别出 1 与 2 的配对很便宜，但是当扩展到 k=2 时，`best`变量允许重新考虑早期的选择，最终的最优配置根据确切的成本变成（1,2）和（11,12）或（2,10）型结构，始终保持全局最优性。 

另一种边缘情况是，除了单个大间隙之外，点紧密聚集。 该算法正确地避免了跨越间隙的配对，除非被迫，因为`best`状态总是编码最小可能的左端点成本，而不是任意的配对决策。
