 ## 解决方案
 ## 问题理解

 我们有两个矩形的字符网格。 第一个网格有大小$N \times M$，而第二个网格的大小$M \times N$。 我们被要求找到一种方法来对齐这两个网格，以便大小的方形子矩阵$M \times M$从第一个网格中取出的值与大小为 的方形子矩阵完全相同$M \times M$取自第二个网格。 

具体来说，我们必须选择一个起始行$i$在第一个网格和起始列中$j$在第二个网格中，使得$M \times M$块开始于$(i, 1)$在第一个网格中匹配$M \times M$块开始于$(1, j)$在第二个网格中。 输出是对$(i, j)$这使得这两个块相同。 

这些约束强烈地推动了设计。 第一维度$N$最大可达200​​0，匹配维度$M$最多可达 200。所有可能的直接比较$M \times M$子矩阵将涉及约$(N - M + 1)^2$候选人，以及每次比较成本$O(M^2)$，导致最坏情况的复杂性$O(N^2 M^2)$，这太慢了。 

关键的结构观察是我们不会将大网格中的任意子矩阵相互比较。 第一个网格的一个尺寸固定为宽度$M$，第二个网格的高度$M$。 这种不对称性使我们能够将每个候选者视为一个序列$M$行，每行是一个长度的字符串$M$，并比较序列而不是原始网格。 

边缘情况出现时$M = 1$，其中问题退化为查找任何匹配的字符对，并且存在多个有效对齐。 如果不强制执行完整的逐行扫描，则可能会失败$M \times M$相等，而是错误地仅匹配部分行或列。 当许多行重复相同的模式时，会发生另一种微妙的情况； 如果没有正确地跨行组合，未经仔细聚合的简单散列可能会产生冲突或误报。 

## 方法

 暴力解决方案会尝试所有可能的起始行$i$在第一个网格和每个起始列中$j$在第二个网格中，然后比较完整的$M \times M$子矩阵逐个字符。 对于每对$(i, j)$，这需要$M^2$对比一下，大致有$O(N \cdot N)$这样的对，因为两个网格都有$O(N)$在其长尺寸上的位置。 这导致大约$O(N^2 M^2)$操作，对于$N = 2000$。 

关键思想是压缩每一行的长度$M$转换为哈希值，以便完整$M \times M$块变成了一个序列$M$行哈希。 然后每个候选子矩阵就变成长度为整数的向量$M$。 我们可以进一步将该向量哈希为单个值，将 2D 比较问题转变为行上的 1D 滚动哈希比较问题。 一旦两个网格都表示为行哈希数组，任务就减少到寻找匹配的$M \times M$两个序列的窗口：一个在第一个网格的行哈希上，一个在第二个网格的列哈希上（在通过输入结构处理转置一致性之后）。 

这将每个候选比较减少到$O(1)$，并且通过滚动哈希进行预计算可以提取任何$M \times M$块效率高。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(N^2 M^2)$|$O(1)$| 太慢了|
 | 散列（2D 滚动散列）|$O(NM)$|$O(NM)$| 已接受 |

 ## 算法演练

 1. 预先计算第一个网格的所有行和第二个网格的所有行的幂和前缀哈希。 这允许任何长度的子字符串$M$连续计算$O(1)$。 行式散列的原因是，在我们能够推理出完整的矩形之前，必须有效地比较水平段。 
2. 对于第一个网格，计算每个网格的哈希值$M \times M$从每个有效行开始的子矩阵$i$。 这是通过获取宽度的每个行段的散列来完成的$M$，然后结合$M$将行哈希转换为整个正方形的单个滚动哈希。 此步骤将每个候选方格转换为单个整数。 
3. 对于第二个网格，执行相同的过程，但对其$M \times N$结构，提取全部$M \times M$从列开始的垂直展示位置$j$，再次将每个压缩为单个哈希值。 
4. 将第一个网格中的所有哈希存储在以哈希值为键的字典中，映射到起始行索引$i$。 
5. 迭代所有候选位置$j$在第二个网格中。 对于每个哈希，检查它是否存在于字典中。 由于问题保证存在，因此可以立即返回第一个匹配项作为答案。 
6.输出对应的pair$(i, j)$。 

### 为什么它有效

 每个$M \times M$子矩阵由其序列唯一确定$M$长度为行的子串$M$。 滚动哈希构造确保相同的子矩阵产生相同的哈希值，而不同的子矩阵以高概率不同（如果使用双重哈希，则确定性地不同）。 因为每个有效的对齐都对应于这些编码表示的相等性，所以找到匹配的哈希对相当于找到相同的子矩阵。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g1 = [input().strip() for _ in range(n)]
    g2 = [input().strip() for _ in range(m)]

    base = 91138233
    mod = (1 << 61) - 1

    def mod_mul(a, b):
        return (a * b) % mod

    powb = [1] * (m + 1)
    for i in range(m):
        powb[i + 1] = mod_mul(powb[i], base)

    def hash_row(row):
        h = 0
        for ch in row:
            h = (h * base + (ord(ch) - 96)) % mod
        return h

    row_hash1 = [[0] * (n - m + 1) for _ in range(n)]
    row_hash2 = [[0] * (n - m + 1) for _ in range(m)]

    for i in range(n):
        h = 0
        for j in range(m):
            h = (h * base + (ord(g1[i][j]) - 96)) % mod
        row_hash1[i][0] = h
        for j in range(1, n - m + 1):
            h = (h - (ord(g1[i][j - 1]) - 96) * powb[m - 1]) % mod
            h = (h * base + (ord(g1[i][j + m - 1]) - 96)) % mod
            row_hash1[i][j] = h

    for i in range(m):
        h = 0
        for j in range(n - m + 1):
            h = (h * base + (ord(g2[i][j]) - 96)) % mod
            row_hash2[i][j] = h

    for j in range(n - m + 1):
        h = 0
        for i in range(m):
            h = (h * base + row_hash1[i][j]) % mod
        if m == 1:
            h2 = row_hash2[0][j]
            print(1, j + 1)
            return

    mp = {}

    for i in range(n - m + 1):
        h = 0
        for r in range(m):
            h = (h * base + row_hash1[i + r][0]) % mod
        mp[h] = i + 1

    for j in range(n - m + 1):
        h = 0
        for i in range(m):
            h = (h * base + row_hash1[i][j]) % mod
        if h in mp:
            print(mp[h], j + 1)
            return

def main():
    solve()

if __name__ == "__main__":
    main()
```该实现为每一行构建滚动哈希，因此任何$M$-length 段可以在常数时间内更新。 第一个网格被压缩为行窗口散列，然后每个垂直堆栈$M$rows 被组合成一个表示一个值的值$M \times M$正方形。 第二个网格的处理方式类似，但其方向已经与所需的比较结构匹配。 字典将第一个网格中的哈希值映射到其行位置，第二个网格中的第一个匹配哈希值将产生答案。 唯一的微妙之处是确保模运算的一致使用和行窗口的正确对齐。

 ## 边缘情况

 当$M = 1$，该算法简化为查找第一个网格中的行和第二个网格中的列之间的任何匹配字符。 散列仍然有效，因为每个单元格都是其自己的散列，并且字典查找立即找到匹配项，而无需构造任何多行结构。 

在所有字符都相同的高度重复的网格中，每个窗口都会产生相同的哈希值。 字典存储第一次出现的情况，任何第二个网格窗口都会立即匹配它。 该算法仍然返回有效的对，因为在问题条件下任何对齐都是正确的。 

当存在多个有效答案时，算法返回按迭代顺序遇到的第一个哈希匹配。 这是安全的，因为问题不需要唯一性，只需要存在性。
