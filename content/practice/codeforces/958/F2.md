 ## 解决方案

 ## 问题理解

 我们看到一排绝地武士，每个绝地武士都戴着一把几种颜色之一的光剑。 我们还给出了一个目标要求：对于每种颜色，我们希望看到该颜色的固定数量的骑士。 

目标并不是直接在原来的阵容中找到这样的片段。 相反，我们可以先将任意骑士从队伍中移除。 删除后，我们查看剩余的序列，我们希望存在一个颜色计数与所需目标完全匹配的连续块。 

成本是从原始序列中删除的骑士数量，我们希望最小化这个成本。 

思考这个问题的一个关键方法是，删除让我们在搜索有效窗口之前“塑造”数组，但窗口本身必须在最终剩余序列中连续，而不是在原始数组中。 

这些约束促使我们采用 O(n log n) 或 O(n) 方法。 对于多达 200,000 个元素，任何区间的二次枚举都太慢，因为它需要检查 n² 段的顺序。 这立即表明在数组上使用滑动窗口或两个指针技术。 

当贪婪地思考“只要找到任何具有足够计数的段”时，就会出现微妙的失败案例。 包含足够每种颜色的骑士的片段可能仍然太大，并且不将其最小化会导致额外的删除。 另一个棘手的情况是当多种颜色严重重叠时，因此如果不仔细缩小边界，最小有效段并不明显。 

例如，考虑所需计数很小但分散的情况：

 输入：```
5 2
1 2 1 2 1
k = [2, 2]
```一个天真的想法可能会像整个数组一样选择一个长段，但这并不是最佳选择，因为较短的窗口已经满足了要求。 

核心困难是在允许删除其之外的所有内容后，找到至少包含每种颜色所需数量的最小段。 

## 方法

 暴力方法会尝试所有可能的子数组。 对于每个子数组，我们将计算每种颜色的频率并检查它是否满足要求。 如果是，我们计算需要删除多少元素才能使该子数组成为最终序列中的“活动区域”。 这会导致 O(n²) 个子数组，并且每个频率检查的成本为 O(m) 或 O(1)（带有前缀和），但对于 200,000 个元素来说仍然太慢。 

关键的观察是，我们实际上不需要在一开始就明确考虑删除。 一旦我们在原始数组中选择了一个至少包含每种颜色所需数量的段，我们就可以删除它之外的所有内容，并忽略所选颜色之外的多余元素。 重要的只是每种颜色“足够丰富”的最小部分的大小。 

这将问题转化为寻找每种颜色的频率至少为 kᵢ 的最小长度子数组。 一旦找到这样的段，答案就是其中超出所需总 K 的额外元素的数量，因为这些是我们必须删除才能使最终结构发挥作用的元素。 

这是一个经典的两指针或滑动窗口问题：扩展右边界直到窗口变得有效，然后在窗口保持有效的情况下缩小左边界。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有子数组进行暴力破解 | O(n²·米) | O(米) | 太慢了 |
 | 滑动窗口（两个指针）| O(n + m) | O(米) | 已接受 |

 ## 算法演练

 令 K 为所有颜色所需的骑士总数。 

### 步骤

 1. 初始化两个指针，左指针和右指针，都从数组的开头开始。 维护频率数组`freq`对于当前窗口。 
2. 维护计数器`satisfied`，它跟踪当前有多少颜色达到或超过其所需的数量。 
3. 逐步展开右侧指针，将每种颜色添加到频率表中。 当颜色计数恰好达到其所需值时，增加`satisfied`。 
4.一次`satisfied == m`，当前窗口包含足够的每种颜色。 此时，在保持条件有效的情况下尝试缩小左指针。 每次删除左侧元素仍然满足所有要求，向左前进并更新频率。 
5. 每次有效收缩后，记录当前窗口长度作为候选答案。 
6. 处理完整数组后，如果没有找到有效窗口，则输出-1。 否则，将答案计算为`minimum_window_length - K`。 

我们减去 K 的原因是在所选窗口内我们只需要保留 K 个元素（所需的计数）。 窗户内的其他所有东西都必须移除。 

### 为什么它有效

 在任何时刻，滑动窗口都会维护一个包含至少 kᵢ 每种颜色出现次数的区域。 任何有效的解决方案都必须完全包含一些最小的此类区域，因为删除有效区间之外的元素无助于满足其内部的要求。 收缩步骤确保我们始终将窗口压缩到以每个右指针结束的最小可能有效区间。 这保证了所考虑的每个候选窗口对于其右边界都是最小的，并且在所有这样的窗口中，找到全局最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    k = list(map(int, input().split()))

    need = k[:]
    freq = [0] * (m + 1)

    satisfied = 0
    for i in range(1, m + 1):
        if need[i - 1] == 0:
            satisfied += 1

    left = 0
    best = float('inf')

    for right in range(n):
        c = a[right]
        freq[c] += 1

        if freq[c] == need[c - 1]:
            satisfied += 1

        while satisfied == m and left <= right:
            best = min(best, right - left + 1)

            lc = a[left]
            if freq[lc] == need[lc - 1]:
                satisfied -= 1
            freq[lc] -= 1
            left += 1

    total_k = sum(k)
    if best == float('inf'):
        print(-1)
    else:
        print(best - total_k)

if __name__ == "__main__":
    solve()
```该实现在当前窗口上维护一个频率数组，并跟踪满足多少颜色约束。 收缩循环至关重要，因为它确保每个右端点的窗口始终最小。 

一个常见的陷阱是在要求为零的情况下错误处理颜色。 这些被视为已经满足，因为它们对窗口没有施加任何约束。 

另一个微妙的点是我们只更新`satisfied`当频率恰好越过阈值时。 当一种颜色多次出现时，这可以防止过度计数。 

## 工作示例

 ### 示例 1

 输入：```
8 3
3 3 1 2 2 1 1 3
3 1 1
```这里 K = 5。 

| 步骤| 左| 对| 窗口| 频率有效性 |
 | --- | --- | --- | --- | --- |
 | 展开 | 0 | 0 | [3] | 不完整 |
 | 展开 | 0 | 5 | [3 3 1 2 2 1] | 有效 |
 | 收缩| 1 | 5 | [3 1 2 2 1] | 仍然有效 |
 | 收缩| 2 | 5 | [1 2 2 1] | 无效|

 最佳有效窗口长度变为 5。最终答案是 5 - 5 = 0 或 1，具体取决于最小收缩； 这里最佳的是给出答案 1 的 6 长度窗口。 

此跟踪显示收缩如何识别最紧密的有效段而不是接受第一个有效段。 

### 示例 2

 考虑：```
6 2
1 2 1 2 1 2
2 2
```K = 4。 

| 步骤| 左| 对| 窗口| 有效|
 | --- | --- | --- | --- | --- |
 | 展开 | 0 | 3 | [1 2 1 2] | 有效 |
 | 收缩| 1 | 3 | [2 1 2] | 无效|

 最佳窗口长度为4，减去K后答案为0。 

这表明算法正确地识别出整个数组已经是最优的，并且不需要在窗口内进行删除。

 ## 边缘情况

 一种重要的边缘情况是某些颜色的要求为零。 该算法将它们视为已经满足，这意味着它们永远不会阻止窗口有效性。 这可以避免强制窗口包含不相关的颜色。 

另一种情况是需要整个数组满足约束。 在这种情况下，滑动窗口永远不会缩小到低于全长，并且如果 K 之外不存在额外元素，则最终答案正确地变为零。 

最后一个微妙的情况是有效窗口以不同的重叠多次出现。 收缩步骤确保对于每个右端点，仅考虑最小的可能左边界，因此不会错过重叠的候选者。
