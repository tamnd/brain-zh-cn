 ## 解决方案

 ## 问题理解

 每艘船都根据“(a + b) / c”形式的简短算术表达式独立计算目标坐标，其中 a、b 和 c 是小正整数。 对该表达式求值后，结果是一个有理数。 获得完全相同价值的船舶最终会到达相同的目的地。 

任务不是计算任何几何或模拟运动。 它简化为评估每个表达式，按相同的结果对船舶进行分组，并为每艘船舶报告有多少艘船舶共享其最终值。 

约束 m 高达 200,000 意味着任何比较每对船的解决方案都是不可能的。 在最坏的情况下，二次方法将执行大约 4 × 10^10 比较，这远远超出了 5 秒的限制。 这迫使采用一种策略，其中每个表达式都被处理一次，并使用标准化表示和散列或计数在恒定或接近恒定的时间内测试相等性。 

如果值存储为浮点数，则会立即出现幼稚的实施风险。 尽管 a、b 和 c 很小，但 (1+2)/3 和 (2+1)/3 等表达式在有理算术中是精确的，但浮点舍入可能会产生微小的差异，从而导致不正确的分组。 另一个微妙的问题是比较没有约简的分数。 例如，(2+2)/4 等于 (1+1)/2 等于 1，但存储原始分子和分母会将它们视为不同的，除非进行标准化。 

## 方法

 暴力策略将每个表达式计算为一个分数，并将其与所有其他表达式进行比较。 每个评估都很简单，但成对比较 m 个结果会导致 O(m²) 比较。 当 m = 200,000 时，这是不可行的。 

关键的观察是我们根本不需要成对比较。 我们只需要知道每个不同值出现的次数。 一旦将值放入规范形式，这就是一个经典的频率计数问题。 主要困难是定义 (a + b) / c 的表示，以保证两个相等的有理数映射到完全相同的键。 

直接浮点计算是不安全的。 相反，我们将每个表达式视为有理数，并使用最大公约数来减少它。 分子是 a + b，分母是 c，我们通过将两者除以 gcd(分子, 分母) 来进行归一化。 这保证了相同的有理值产生相同的约简对。 

一旦每个表达式都映射到规范对 (p, q)，我们就将计数存储在哈希映射中。 最后，我们输出每个原始表达式的频率。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(平方米) | O(1) | O(1) | 太慢了|
 | 最优（哈希+标准化）| O(米) | O(米) | 已接受 |

 ## 算法演练

1. 一一读出所有的表达方式。 对于每个字符串，通过解析固定位置或围绕已知符号进行拆分来提取 a、b 和 c。 格式是严格的，因此解析是确定性的且时间恒定。 
2. 计算分子值 n = a + b。 这表示除法之前的完整整数部分。 
3. 将结果表示为有理数 n / c。 此时，求值为相同值的不同表达式可能仍具有不同的表示形式。 
4. 通过计算 g = gcd(n, c) 来减少分数。 将分子和分母同时除以 g，生成归一化对 (n/g、c/g)。 此步骤确保等价的有理数始终折叠成相同的表示形式。 
5. 将每个归一化对存储在频率图中。 键是元组（分子，分母），值是迄今为止出现的次数。 
6. 处理完所有表达式后，按原始顺序再次迭代存储的归一化对并输出每个表达式的频率。 

我们首先存储所有结果的原因是每个输出取决于全局频率，而不是增量状态。 

### 为什么它有效

 每个表达式定义一个有理数 (a + b) / c。 两个表达式相等当且仅当它们的约化分数相同。 gcd 归一化保证了表示的唯一性：每个有理数恰好映射到一对不可约整数。 因为 Python 字典在元组上使用结构相等，所以相同的分数会碰撞到相同的键，并且计数变得精确。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from math import gcd

def parse(expr):
    # format: (a+b)/c
    # strip parentheses and split manually
    # expr example: (12+33)/15
    expr = expr.strip()
    expr = expr[1:]  # remove '('
    plus_idx = expr.find('+')
    slash_idx = expr.find('/')
    a = int(expr[:plus_idx])
    b = int(expr[plus_idx + 1:slash_idx - 1]) if expr[slash_idx - 1] == ')' else int(expr[plus_idx + 1:slash_idx])
    # safer direct parsing ignoring ')'
    if expr[slash_idx - 1] == ')':
        b_str = expr[plus_idx + 1:slash_idx - 1]
    else:
        b_str = expr[plus_idx + 1:slash_idx]
    b = int(b_str)
    c = int(expr[slash_idx + 1:])
    return a + b, c

def main():
    m = int(input())
    nums = []
    denoms = []
    freq = {}

    for _ in range(m):
        expr = input().strip()
        n, d = parse(expr)
        g = gcd(n, d)
        n //= g
        d //= g
        nums.append(n)
        denoms.append(d)
        freq[(n, d)] = freq.get((n, d), 0) + 1

    res = []
    for i in range(m):
        res.append(str(freq[(nums[i], denoms[i])]))

    print(" ".join(res))

if __name__ == "__main__":
    main()
```解析逻辑依赖于表达式的固定结构。 由于每个表达式都严格遵循“(a+b)/c”，因此我们找到加号和斜杠字符并相应地提取子字符串。 我们明确避免浮点运算，只使用整数。 

gcd归一化是确保正确性的关键步骤。 如果没有它，像 (2+2)/4 和 (1+1)/2 这样的值将产生不同的键，即使它们代表相同的有理数。 

我们将分子和分母分别存储在列表中，以便第二遍可以按原始顺序输出答案而无需重新计算。

 ## 边缘情况

 一种重要的边缘情况是不同的表达式简化为相同的有理数但在语法上不相同。 例如 (10+10)/20 和 (5+5)/10 都计算为 1。如果没有 gcd 缩减，它们将产生不同的键并单独计数。 归约后，两者都变为 (1,1)，并且频率图将它们正确分组。 

另一种情况是分子和分母已经互质。 对于 (5+1)/7 这样的表达式，gcd(6,7) = 1，因此表示形式保持不变。 该算法仍然可以正常工作，因为归一化是幂等的并且不会改变已经减少的分数。 

最后一个微妙的情况是解析依赖于固定格式。 因为输入保证了严格的模式，没有空格，并且恰好有一个 + 和一个 /，所以子字符串解析是安全的。 任何与此格式的偏差都需要完整的表达式解析器，但问题设计完全避免了这种复杂性。
