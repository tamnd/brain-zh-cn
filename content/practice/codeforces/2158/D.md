 ## 解决方案
 ## 问题理解

 我们有两个长度相等的二进制字符串。 将它们视为两排开关，每个位置要么关闭，要么打开。 任务是通过重复选择一个段并翻转该段中的所有位，将第一行转换为第二行。 

不同的是，并非每个片段都被允许。 仅当在操作时，我们选择的子字符串向前和向后读取相同时，才可以翻转段。 选择这样的回文段后，我们反转其中的每一位。 

我们必须确定是否可以使用最多使用次数将初始字符串转换为目标字符串$2n$此类操作，如果是，则输出一个有效的操作序列。 

关键的限制是$n \le 100$，而总和$n^2$所有测试用例都是有界的。 这强烈表明$O(n^2)$甚至$O(n^3)$每个测试用例都是可以接受的，而任何指数级的位置则不可接受。 

天真的阅读可能会认为这是字符串上的最短路径问题，其中每个状态都有许多转换，但这种观点具有误导性，因为有效操作的结构极其严格：回文子串的行为是对称的，翻转它们可以保留这种对称性。 

当字符串已经相等时，会出现一种微妙的边缘情况。 任何总是试图“贪婪地修复不匹配”的粗心策略仍然可能尝试翻转并打破相等性，但正确的输出必须允许零操作。 

另一个重要的边缘情况是在一个位置处隔离不匹配时。 一种简单的方法可能会尝试使用 length-1 操作来修复它，但不允许使用单个字符，因为$l < r$。 这迫使我们始终使用成对或更大的对称结构。 

最后，在某些配置中，局部贪婪修复可能会破坏先前固定的位置。 这就是为什么构造必须保持全局不变量而不是独立固定位置。 

## 方法

 强力视点将每个字符串建模为图中的一个节点，并将每个有效的回文翻转建模为一条边。 那么问题就变成了寻找一条路径$s$到$t$。 这在概念上是正确的，但完全不可行，因为每个州都有$\Theta(n^2)$可能的操作，状态数为$2^n$。 就算是BFS也会立刻爆炸。 

一旦我们停止考虑任意回文段，而是关注不匹配在对称操作下如何传播，该结构就变得易于管理。 

关键的观察是我们永远不需要任意的回文片段。 我们可以将自己限制为以下操作：

 在校正对时保持中心周围的对称性，或者在需要时对整个字符串执行完全反转的校正。 

这是可能的，因为回文子串强制每个操作一致地处理对称索引。 如果我们翻转一个回文，位置$i$和$n-i+1$总是以受控的方式共同受到影响。 

这导致了一个建设性的策略：我们从外向内对齐字符串，固定对称对$(i, n-i+1)$逐个。 每当存在不匹配时，我们都会使用精心选择的回文段，其中包含纠正该对所需的结构，而不会破坏早期的修复。 

在最坏的情况下，每个位置被触摸的次数是恒定的，并且每个操作都可以在$O(n)$，得到整体二次解。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（字符串上的图 BFS）|$O(2^n \cdot n^2)$|$O(2^n)$| 太慢了|
 | 最优构造回文固定 |$O(n^2)$|$O(n)$| 已接受 |

 ## 算法演练

 我们维护一个工作字符串$s$我们修改直到它匹配$t$。 该结构始终保持已处理后缀的正确性。 

1.我们从最外层向内处理字符串，配对索引$i$和$n-i+1$。 这确保了对称性得到一致的处理，并减少了固定对的问题。 
2.如果$s[i] = t[i]$和$s[n-i+1] = t[n-i+1]$，我们对这一对不做任何事情，而是向内移动。 这避免了可能干扰后续结构的不必要的操作。 
3. 如果该对中的两个位置已经匹配其目标但彼此不一致，我们仍然不执行任何操作，因为仅需要相对于最终目标的一致性，而不需要内部对称性。 
4. 如果两个位置中的一个与其目标不同，我们构造一个包含两个索引并居中的回文段，以便该段围绕字符串的中点或围绕覆盖的局部对称中心对称$i$和$n-i+1$。 这样做的原因是翻转回文会同时改变两个对称位置，使我们能够通过一次操作来修复这两个位置。 
5. 如果两个位置不同，我们同样使用更大的回文段，以确保两个位在需要时准确翻转。 该结构保证在一次或两次操作之后，该对被纠正，而不会影响先前固定的外部对。 
6. 我们重复此过程，直到解决所有对。 的界限$2n$操作受到尊重，因为每个步骤要么解决至少一个新的失配对，要么永久对齐对称结构。 

中心不变量是迭代完成后$i$，区间外的所有位置$[i, n-i+1]$已经与目标字符串匹配，并且永远不会被任何未来选择的回文再次修改。 这是可以保证的，因为每个选定的片段都完全包含在当前未解析的区域内，并且回文对称性可以防止意外泄漏到其外部。 

正确性源自以下事实：每个操作都会将对称位置翻转在一起，并且我们总是选择与剩余未解析结构对齐的片段。 任何早期的固定头寸都不在未来操作的活动范围内。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input().strip())
        s = list(input().strip())
        t = list(input().strip())

        ops = []

        def is_pal(l, r):
            while l < r:
                if s[l] != s[r]:
                    return False
                l += 1
                r -= 1
            return True

        def flip(l, r):
            for i in range(l, r + 1):
                s[i] = '1' if s[i] == '0' else '0'
            ops.append((l + 1, r + 1))

        for i in range(n // 2):
            j = n - 1 - i

            if s[i] == t[i] and s[j] == t[j]:
                continue

            if s[i] != t[i] and s[j] != t[j]:
                if is_pal(i, j):
                    flip(i, j)
                else:
                    k = i + 1
                    while k < j and s[i] == s[k]:
                        k += 1
                    if k < j:
                        flip(i, k)
                        flip(i, j)
            else:
                if is_pal(i, j):
                    flip(i, j)
                else:
                    k = i + 1
                    while k < j and s[i] == s[k]:
                        k += 1
                    flip(i, k)
                    flip(i, j)

        if s == t:
            print(len(ops))
            for l, r in ops:
                print(l, r)
        else:
            print(-1)

if __name__ == "__main__":
    solve()
```该实现保留了字符串的可变列表表示，因此翻转是高效的。 帮手`is_pal`检查当前段是否是回文段，这是执行任何操作之前必需的。 功能`flip`执行实际操作并将其记录在从 1 开始的索引中。 

主循环处理对称对$(i, j)$。 当两端都错误时，我们可能需要一到两次操作，具体取决于该段是否已经是回文。 如果不是，我们首先通过翻转对齐字符的前缀段来创建一个有效的回文结构，然后将校正扩展到整个间隔。 这种分阶段修复避免了违反回文约束。 

必须小心索引，特别是确保$l < r$总是成立。 的选择$k$确保我们永远不会尝试单字符翻转。

 ## 边缘情况

 当$s = t$，算法立即终止而不生成操作。 这避免了不必要的翻转，否则可能会破坏正确性。 

当整个字符串已经是回文但相对于目标相反时，对$[1, n]$就足够了。 由于整个字符串是对称的，因此它在开始时总是满足回文条件。 

当不匹配在末端附近被隔离时，算法始终向内扩展所选段，直到找到有效的回文子串。 因为我们只在未解析的区域内移动，所以不会触及之前固定的字符，从而在迭代中保持正确性。
