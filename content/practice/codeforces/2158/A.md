[CF 2158A - 暂停](https://codeforces.com/problemset/problem/2158/A)

 **求解时间：** 1m 11s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们进行一场有固定人数球员的足球比赛，并以黄牌和红牌的形式进行一系列纪律处分。 每张黄牌都会导致潜在的停赛，而每张红牌都会立即停赛一名球员。 球员可以通过两种不同的方式被停赛：要么直接吃到红牌，要么累计两张黄牌。 

关键的限制是，一旦玩家被暂停，任何其他发给他们的牌都无关紧要，因为他们不再在游戏中。 我们没有被要求模拟随着时间的推移真实的牌分布，而是根据黄牌和红牌的总数来确定最终可能被停赛的不同球员的最大数量。 

因此，假设我们以最有利的方式分配牌，每个测试用例的输出就是可以离开游戏的最大可能玩家数量。 

限制很小，每次测试最多 100 名玩家，最多 500 个测试用例。 这立即表明，即使每个测试用例有一个直接推理或恒定时间公式也足够了。 即使是 n 中的二次方仍然可以轻松通过，但问题的结构强烈暗示我们正在寻找封闭形式的贪婪分配而不是模拟。 

当黄牌较多而红牌很少时，就会出现微妙的边缘情况。 例如，如果我们有很多黄色但很少有红色，我们必须决定是通过将​​黄色分组成对还是将它们分配给玩家来“浪费”黄色。 另一个极端情况是，仅红牌就已经超过了球员数量，因为每个红牌最多对应一次停赛。 

一个幼稚的错误是单独处理黄牌，将每张黄牌都视为潜在的停赛。 但这种做法失败了，因为单次停赛需要两张黄牌，而如果没有足够的球员来成对使用，那么剩下的单张黄牌可能无法使用。 

## 方法

 暴力解释将尝试模拟将每张黄牌和红牌分配给各个球员，并分支所有可能的分配。 每张卡都可以分配给任何仍然活跃的玩家，并且每次分配都可能会改变玩家是否被暂停。 这很快就会导致爆炸：对于最多 2n 张卡中的每张，最多有 n 个选择，使得搜索空间达到 n^(2n) 的量级，即使对于 n = 100，这也是完全不可行的。 

关键的观察是，我们实际上并不关心玩家的身份，只关心可以创建多少个暂停。 每张红牌最多可独立产生一名禁赛球员，每对黄牌也可产生一名禁赛球员。 由于玩家在容量方面是无法区分的（每个玩家只能被暂停一次），因此问题就简化为计算我们可以从可用资源中形成多少个不相交的“暂停单元”。 

Each red card is already a full unit. 对于黄牌，每两张黄牌为一个单位。 因此，基于黄色的悬浮液的数量受到下限（y / 2）的限制。 红队和黄队之间的唯一联系是我们不能超过 n 名被禁赛的球员。 

所以答案是三个量中的最小值：球员数量n、红牌数量r、以及可能的暂停单元总数r+floor(y/2)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力分配| O(n^(2n)) | O(n^(2n)) | O(n) | 太慢了|
 | 贪心计数| 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们使用直接计数策略计算每个测试用例的答案。

1. 计算有多少名球员可能因红牌而被禁赛。 每张红牌都会暂停一名不同的球员，因此这会导致潜在的停赛。 
2. 计算黄牌可以造成多少次停赛。 由于每次停赛需要两张黄牌，我们占据发言权（y / 2）。 这给出了全黄色悬浮液的数量。 
3. 将这两个来源相加即可得到“可用暂停位置”的总数，而不考虑玩家限制。 
4. 将结果限制为 n，因为总共只有 n 名球员可以被暂停。 
5. 输出最终值。 

关键的推理步骤是，红牌停赛和黄牌停赛是球员“消耗”的独立来源。 每个只使用一名球员，并且任何球员都不能被计算两次。 

### 为什么它有效

 在任何最佳安排下，每次停赛都恰好对应于一名球员被分配一张红牌或至少两张黄牌。 由于红牌不能分开，而黄牌只成对出现，我们能做的最好的事情就是最大限度地增加我们可以形成多少个大小为 1（红色）或 2（黄色对）的不相交组，仅取决于 n 个玩家的可用性。 没有任何相互作用可以使总悬浮量增加到超过 r+floor(y/2)，并且没有任何重新排列可以超过 n。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    y, r = map(int, input().split())

    yellow_susp = y // 2
    ans = r + yellow_susp
    print(min(n, ans))
```直接按照推导公式实现。 我们使用整数除法计算存在多少个全黄对，然后添加红牌的数量。 最后，我们通过 n 来限制可用玩家的数量。 

唯一微妙的一点是确保对黄牌使用整数除法，因为任何剩余的单黄牌在没有配对的情况下都不会导致暂停。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        y, r = map(int, input().split())
        out.append(str(min(n, r + y // 2)))

 ## 边缘情况

 一个关键的边缘情况是，当黄色数量充足但由于玩家限制而无法全部配对到暂停中时。 例如，n = 4、y = 10、r = 0。该算法计算 y // 2 = 5，但 r + y // 2 = 5 超过 n。 最终正确的答案是 4，因为只有 4 名玩家存在。 任何在不认识全局上限的情况下贪婪地为每个玩家分配黄色的尝试都会错误地多算。 

另一种边缘情况是红色已经超过 n 时。 对于 n = 3、r = 5、y = 0，我们计算红方 5 次暂停，但只有 3 名球员存在，因此答案为 3。该公式通过 min(n, ...) 正确处理此问题，防止无效的过度分配。 

最后一个微妙的情况是黄色数量为奇数。 对于n = 6，y = 5，r = 0，我们得到y // 2 = 2。剩下的单个黄色无法使用，答案是2，这与一个黄色必须保持不成对且不能单独形成悬浮液的事实相匹配。
