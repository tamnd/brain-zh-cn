 ## 解决方案
 ## 问题理解

 我们有一条街道，有几家商店，每家商店都以固定价格提供相同类型的产品。 在每家商店中，价格都是对称的：如果您在那里购买或出售一件商品，则成本或收入的价值完全相同。 每个商店还限制您与其互动的次数，并且每次互动要么购买或出售一个单位。 

您一开始就有无限的资金，因此您永远不会被阻止购买。 目标是在所有商店中执行一系列购买和销售操作，以最大化总利润，其中利润是销售总收入减去购买总成本。 

一个关键的结构限制是每个商店只能使用有限的次数，但您在全球范围内可以持有或交易的总物品数量没有限制。 这将问题转变为在容量限制下跨价格点网络选择一组最佳交易。 

约束足够大，任何直接考虑所有商店对的解决方案都是不可能的。 每个测试用例最多有 100,000 个商店，并且测试总数最多为 10^6，O(n^2) 策略将远远不可行。 即使 O(n log n) 或 O(n log^2 n) 也是可以接受的，但必须避免任何隐式枚举对的情况。 

当所有价格都相同时，就会出现微妙的边缘情况。 在这种情况下，即使有许多有效的买卖序列是可能的，也不存在有利可图的交易。 不强制利润正值的天真贪婪者可能会通过配对相等的值来错误地产生非零利润。 

当产能很大但价格仅略有不同时，就会出现另一种失败情况。 例如，如果低价出现在输入订单中较晚，则不对商店进行全局重新排序的幼稚方法将错过最佳交叉配对机会。 

## 方法

 在较高层面上，每个动作要么以某个价格购买一个单位，要么以某个价格出售一个单位。 如果我们看整个过程结束后，每一个买入的单位最终都必须卖出，否则就会贡献负利润。 因此，该过程可以被视为将买入操作与卖出操作配对，其中每对产生的利润等于卖出价减去买入价。 

这减少了从多重集中选择值对的问题，其中每个商店最多贡献其价格的双份副本。 每个副本最多可以用作买入或卖出一次，因此最终结构实际上是一个多重集匹配问题：我们希望将低值与高值匹配，尊重多重性。 

强力解释将明确地将每个商店扩展为两个相同的元素，然后尝试买卖之间所有可能的匹配。 这立即变得不可行，因为在最坏的情况下，总扩展大小可能高达 10^11。 

关键的观察是，当存在更好的替代方案时，最佳策略永远不会将高位买入与低位卖出配对。 如果我们按照价格递增的顺序处理商店，那么任何以价格 ai 的有利可图的销售都应该与最便宜的早期购买相匹配。 这是因为用更便宜的产品替换更昂贵的产品只能提高利润，并且永远不会违反产能限制。 

这导致了一种贪婪的结构，在该结构中，我们保留所有先前可用的买入机会，并且当我们遇到新价格时，我们使用它来针对最便宜的买入执行尽可能多的有利可图的卖出操作。 

因此，我们模拟一个过程，其中我们保留一个可用购买池，始终按成本递增顺序提取，并且在每个商店中，我们充当从该池中消费的卖家。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力扩展+匹配| O(total_bi^2) | O(total_bi^2) | O(total_bi) | 太慢了 |
 | 贪婪最小堆匹配 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们按价格递增对商店进行排序，并维持以前可能的购买操作的结构。 

1.按照价格ai对所有商店进行非降序排序。 这确保了当我们到达商店时，之前存储的每个潜在购买的价格都小于或等于当前价格。 
2. 维护一个最小堆，用于存储候选购买价格以及每个价格仍然可用的次数。 每个条目代表我们之前执行的买入，但尚未与卖出相匹配。 
3. 按排序顺序遍历商店。 当我们以价格 ai 和容量 bi 到达商店 i 时，我们将此商店解释为潜在卖家。 
4. 对于每个可能的卖出操作，我们尝试将其与堆中最便宜的可用买入相匹配。 我们提取可用的最小购买价格。 
5. 如果最便宜的购买价格严格小于 ai，我们将执行交易并将 ai - buy_price 添加到答案中。 如果最便宜的购买价格大于或等于 ai，我们将停止使用该商店进行销售，因为不存在进一步有利可图的配对。 
6. 如果买入条目已耗尽，我们会将其从堆中删除。 如果部分使用后仍有剩余容量，我们会将其推回并更新计数。 
7. 在商店 i 完成销售后，我们通过将 ai 的 bi 副本插入堆中来添加该商店作为购买源。 这确保了未来价格较高的商店可以将其作为廉价购买。 

顺序是强制正确性的：我们只会以未来更高的价格出售，而不会向后出售。 

### 为什么它有效

 在任何时刻，该堆都包含来自商店的所有购买机会，其价格严格小于或等于当前价格。 当我们处理价格为 ai 的商店时，任何有利可图的交易都必须将 ai 与价格小于 ai 的早期购买配对。 在所有此类购买中，使用最小的购买可以为该销售操作产生最大的边际利润，并且它可以为未来更高的销售价格保留更昂贵的购买。 由于未来的商店只会增加价格订单，推迟更便宜的购买永远不会改善任何未来的结果，这保证了贪婪的选择在整个过程中是安全的。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        stores = []
        for _ in range(n):
            a, b = map(int, input().split())
            stores.append((a, b))

        stores.sort()

        # min-heap of available buys: (price, remaining_count)
        # we store as list but manage counts explicitly
        heap = []
        ans = 0

        for a, b in stores:
            # first, use this price as a seller for b operations
            for _ in range(b):
                while heap:
                    price, cnt = heapq.heappop(heap)
                    if cnt == 0:
                        continue
                    if price >= a:
                        # cannot profit; push back and stop
                        heapq.heappush(heap, (price, cnt))
                        heap = heap
                        break

                    # we use one unit
                    ans += a - price
                    cnt -= 1

                    if cnt > 0:
                        heapq.heappush(heap, (price, cnt))
                    break

                else:
                    break

            # then add this store as a buy source
            heapq.heappush(heap, (a, b))

        print(ans)

if __name__ == "__main__":
    solve()
```代码首先对商店进行排序，以便我们按升序处理价格。 该堆存储所有先前可用的购买机会。 对于每家商店，我们尝试通过重复购买最便宜的商品来执行最多双盈利的销售。 如果最便宜的购买无法盈利，我们会立即停止前往该商店，因为所有其他可用的购买都更贵。 

处理销售后，我们插入当前商店作为未来的购买源，因为它稍后可以被价格较高的商店使用。 

一个微妙的实现细节是我们必须在堆内正确处理计数。 每个堆条目都带有剩余的重数，只有当条目的计数变为零时，我们才会删除条目。 

## 工作示例

 考虑一个包含三个商店的小案例：(价格, 容量) = (10, 2), (20, 1), (30, 1)。 排序后，我们先处理10。 堆是空的，所以我们还不能出售任何东西，但我们以价格 10 添加了两次购买。 

| 步骤| 当前（a，b）| 堆（购买）| 行动| 利润|
 | ---| ---| ---| ---| ---|
 | 1 | (10,2) | (10,2) | ∅ | 添加购买 | 0 |
 | 2 | (20,1) | (20,1) | (10×2) | 使用 10 出售一次 | 10 | 10
 | 3 | (30,1) | (30,1) | (10×1) | (10×1) 使用 10 出售一次 | 20 |

 总利润变为 20。 

该轨迹表明，低价商品首先积累，然后被高价商品以贪婪的方式消耗，总是提取最便宜的可用购买。 

现在考虑等价：(5,2)，(5,3)。 排序后，我们添加从第一家商店购买的商品，但使用第二家商店销售时无法盈利，因为价格差异为零。 

| 步骤| 当前（a，b）| 堆| 行动| 利润|
 | ---| ---| ---| ---| ---|
 | 1 | (5,2) | ∅ | 添加购买 | 0 |
 | 2 | (5,3) | (5×2) | (5×2) | 没有盈利的出售| 0 |

 这证实了该算法正确地避免了零利润循环。

 ## 边缘情况

 当所有价格相同时，每个潜在买入的成本与每个潜在卖出的成本相同。 堆将始终产生等于当前价格的价格，因此获利的条件立即失败。 对于像 (7, 10), (7, 10) 这样的输入，算法会累积买入，但从不执行任何卖出，正确地产生零。 

当非常便宜的商店出现较晚时，排序可确保其尽早得到处理。 如果没有排序，天真的遍历将完全错过最佳配对结构，因为有利可图的交易取决于全局排序而不是输入顺序。 

当容量很大时，堆仍然只存储每个价格的聚合计数，因此该算法避免扩展到单个交易，同时保留正确的匹配行为。
