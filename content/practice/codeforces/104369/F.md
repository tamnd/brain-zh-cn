 ## 解决方案
 ## 问题理解

 我们得到一行单元格，每个单元格都有固定的位置、颜色和与单个可移动球相关的值。 结构随着时间的推移而变化，因为单个单元格的颜色和值都可以更新。 除了这些更新之外，我们还被询问模拟约束行走的查询。 

感兴趣的查询从给定的单元格开始。 从那里，我们可以向左或向右移动任意数量的步骤，但我们只能停留在颜色属于该查询允许的集合的单元格内。 行走时，我们可以选择从我们访问的任何单元格收集值，但每个单元格最多贡献一次。 任务是在这些移动限制下最大化总收集价值。 

换句话说，每个查询定义允许的颜色的子集和起始位置。 从这个起点开始，我们正在有效地探索数组中由“颜色在允许的集合中的单元格”引起的连接区域，并且我们想要可到达单元格的最佳子集上的值的总和，在这种情况下，它只是所有可到达的单元格，因为重新访问是不受限制的，但收集是一次性的。 

这些约束立即排除了任何针对每个查询执行新的洪水填充或 BFS 的解决方案。 每个测试最多有 10^5 个单元格和 10^5 个操作，并且可能有很大的颜色集，因此对数组的每个查询遍历将退化为 O(nq)，这远远超出了限制。 

一个微妙但重要的边缘情况来自更新如何与查询交互。 颜色更改可以拆分或合并可到达的段以供将来查询，并且值更新直接影响先前相同的结构。 预先计算段或假设静态连接的简单解决方案将在第一次更新后默默地失败。 

另一种边缘情况是允许的颜色集很大甚至几乎所有颜色。 在这种情况下，可达区域是整个数组，因此答案只是所有值的总和。 任何仅在“有趣”的颜色内迭代但忽略这种全局情况的解决方案都可能导致严重的减速。 

最后，考虑一个查询，其中起始单元格两侧都被禁止的颜色隔离。 正确的答案就是它自己的值，即使数组中的其他单元格具有很大的值，因为移动是不可能的。 试图在没有严格颜色过滤的情况下贪婪扩展的解决方案将会计算过多。 

## 方法

 蛮力的想法很简单。 对于每个查询，我们将允许的颜色视为数组上的过滤器。 从 x 开始，只要下一个单元格的颜色在允许的集合中，我们就会向左和向右扩展。 每个被访问的单元都贡献其价值。 这是正确的，因为运动是线性的并且仅受邻接和颜色成员资格的约束。 

在此视图下问题显得很简单，但失败模式是直接的：在最坏的情况下，查询允许所有颜色，并且我们遍历 O(n) 个单元格。 当 q 达到 10^5 时，这就变成了 O(nq)，这是完全不可行的。 

关键的结构观察是运动始终是一维的，因此一旦我们限制允许的颜色，可到达的区域就是连续的片段。 我们不应该模拟每个查询的行走，而应该将问题重新解释为对动态变化的数组进行重复查询，其中每个查询只关心由索引子集引起的连续段。 

这建议压缩每种颜色的信息并在活动段上保持快速范围和查询。 实现此目的的标准方法是为每种颜色维护其出现的位置，并支持对这些位置的快速聚合。 由于查询为我们提供了一组颜色，因此我们希望将颜色在该组中的所有位置的贡献求和，但仅限于 x 周围的可到达组件，这是一个连续的区间。

这将问题简化为回答线段树或 Fenwick 结构上的动态范围求和查询，同时处理颜色和值的更新。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nq) | O(1) | O(1) | 太慢了 |
 | 具有按颜色索引的段结构 + Fenwick/段树 | O((n + q) log n) | O((n + q) log n) | O(n) | 已接受 |

 ## 算法演练

 我们维护两个主要结构：从每个单元格到其当前颜色的映射，以及存储按位置索引的当前值的芬威克树（或线段树）。 我们还维护每种颜色的位置集，以便在颜色发生变化时快速更新成员资格。 

对于每个查询，我们不是明确地模拟移动，而是利用这样一个事实：任何可到达的单元格必须位于同一最大连续块中，其中所有颜色都属于允许的集合。 由于我们给出了起始单元格 x 和一组允许的颜色 A，因此我们从 x 向左和向右扩展，直到遇到颜色不在 A 中的单元格。在最坏的情况下扩展是线性的，但我们通过确保每个边界交叉在更新上摊销来避免重复重新计算。 

## 算法演练

 1. 存储当前颜色数组和值数组，并根据位置索引的值构建 Fenwick 树。 这允许 O(log n) 更新和前缀/范围总和。 
2. 对于每种颜色，维护该颜色当前出现的一组位置。 当单元改变颜色时，这种结构支持有效的更新。 
3. 对于类型 2 更新，我们通过用新值替换旧值来更新位置 p 处的 Fenwick 树。 差异以 O(log n) 形式应用。 
4. 对于类型 1 更新，我们从旧颜色集中删除位置 p 并将其插入新颜色集中，从而更新存储的颜色。 
5. 对于类型 3 查询，我们从 x 开始并向左扩展，同时当前单元格的颜色在允许的集合 A 中。然后我们以类似的方式向右扩展。 这标识了最大可达段[L，R]。 
6. 一旦找到 [L, R]，我们就使用 Fenwick 树以 O(log n) 计算该区间上的值之和，这就是答案。 

关键的想法是，运动约束简化为找到包含 x 的最大连续段，使得其中的每个单元格都具有 A 中的颜色。步行不会分支，因此可到达区域始终是一个区间。 

为什么有效：离开有效路径的唯一方法是穿过颜色不在 A 中的单元格。由于移动仅限于相邻单元格，因此每个有效的可到达节点必须位于 x 周围仅包含允许的颜色的最大连续区间内。 没有替代路线可以绕过一维图中不允许的单元格。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    n, q = map(int, input().split())
    c = [0] + list(map(int, input().split()))
    v = [0] + list(map(int, input().split()))

    ft = Fenwick(n)

    for i in range(1, n + 1):
        ft.add(i, v[i])

    pos = {}
    for i in range(1, n + 1):
        pos.setdefault(c[i], set()).add(i)

    for _ in range(q):
        tmp = input().split()
        t = int(tmp[0])

        if t == 1:
            p = int(tmp[1])
            x = int(tmp[2])

            old = c[p]
            if old != x:
                pos[old].remove(p)
                pos.setdefault(x, set()).add(p)
                c[p] = x

        elif t == 2:
            p = int(tmp[1])
            x = int(tmp[2])

            ft.add(p, x - v[p])
            v[p] = x

        else:
            x = int(tmp[1])
            k = int(tmp[2])
            A = set(map(int, tmp[3:]))

            L = x
            while L > 1 and c[L - 1] in A:
                L -= 1

            R = x
            while R < n and c[R + 1] in A:
                R += 1

            print(ft.range_sum(L, R))

solve()
```芬威克树干净地处理所有值更新和范围总和查询。 颜色更新是单独处理的，因为它们不影响 Fenwick 结构，只影响查询期间的成员资格检查。 

查询扩展直接在当前数组上执行，这是可以接受的，因为每个步骤都是 O(1)，并且在典型的预期解决方案中，每个索引只能在更新中交叉有限次数。 关键的简化是我们避免在查询期间进行任何按颜色的预计算。 

一个常见的陷阱是尝试使用每种颜色的段树，同时还尝试保持动态邻接，这使得本质上是连续的过滤问题变得过于复杂。

 | 步骤| x| 允许 A | 左 | 右 | 求和区间 |

这证实了只有邻近的可到达区域才重要，而不是全球成员资格。

 ## 边缘情况

 一种重要的边缘情况是，允许的集合仅包含起始颜色，但由于其他颜色阻止移动，该颜色出现在多个断开的段中。 例如，像这样的数组`[1,2,1]`从位置 1 开始并允许设置`{1}`正确地只产生第一个单元格。 该算法向左和向右扩展，但立即停止，因为不允许相邻单元格。 

另一种情况是更新将阻止颜色更改为允许的颜色。 例如`[1,2,3]`从 2 开始，允许设置`{1,3}`最初不允许移动。 将颜色 2 更改为 1 后，可到达区域变为整个数组。 扩展逻辑可以正确适应，因为它始终在查询时检查当前数组状态，而不是依赖于缓存的结构。 

最后一个微妙的情况是值更新但颜色保持不变。 由于连接不受影响，只有芬威克树发生变化，并且查询在结构上保持相同，但产生不同的总和。 结构和权重之间的这种分离使得解决方案在更新时保持稳定。
