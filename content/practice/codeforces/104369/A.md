 ## 问题理解

 我们正在研究一个从第一年开始的年度活动`y1`。 从那一年起，该比赛计划每年举行一次。 然而，有一小部分特殊年份没有举办比赛。 

对于每个测试用例，我们都会得到起始年份、未发生比赛的“跳过”年份的排序列表以及目标年份`y2`。 任务是统计今年实际举办了多少场比赛`y1`全年`y2`，包括两个端点。 

重新构建问题的一个有用方法是考虑年份间隔`[y1, y2]`作为一个连续的序列，每年都会贡献一次潜在的比赛，除了一些特定的年份被从这个计数中删除。 因此，答案就是该间隔内的总年数减去其中跳过的年数。 

的约束条件为`n`最多为 100，而年限为 9999。这立即表明，即使每个测试用例最多执行几百次操作也是微不足道的。 对跳过列表进行线性扫描已经足够了。 

一个微妙的边缘情况是跳过的年份包含查询范围之外的值。 例如，如果`y1 = 2000`,`y2 = 2005`，跳过的一年是`1999`或者`2010`，这些不应该影响答案。 另一个重要的细节是`y2`保证不会是跳过的年份，因此我们永远不需要处理从计数和排除中减去它的歧义。 

## 方法

 思考问题的天真的方法是逐年模拟。 开始于`y1`，我们迭代至`y2`，并且每年我们检查它是否出现在跳过列表中。 如果没有，我们将其视为举行的比赛。 这是正确的，因为它直接遵循流程的定义。 

然而，这种方法做了不必要的工作。 之间的年数`y1`和`y2`可能很大，大约可达 10,000 个，每年我们可能会扫描多达`n = 100`跳过的值。 这导致每个测试用例执行大约 1,000,000 次操作，这在这里仍然处于临界状态，但从概念上讲是浪费并且更难以推理。 

关键的观察是我们实际上不需要每年迭代。 除明确删除的年份外，该竞赛每年都会举行。 因此，答案纯粹是组合性的：范围内的总年份减去同一范围内跳过的年份数。 

这将问题简化为过滤最多 100 个元素的小列表，计算其中的元素`[y1, y2]`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O((y2 - y1 + 1) · n) | O(1) | O(1) | 可以接受但没有必要 |
 | 计算范围内跳过的年份| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 读取起始年份`y1`, 跳过的年份数`n`，以及跳过年份的列表。 我们按照给定的方式存储跳过的年份，因为它们已经排序，但不需要排序。 
2. 读取目标年份`y2`。 
3. 计算该区间内的总年数`[y1, y2]`。 这简直就是`y2 - y1 + 1`，如果没有跳过任何内容，它会计算所有可能的比赛年份。 
4. 迭代每个跳过的年份`s`。 对于每个`s`，检查是否在区间内`[y1, y2]`。 如果是，则从总数中减一。 我们忽略间隔之外的跳过年份，因为它们不会影响我们询问的范围。 
5. 输出结果计数。 

我们可以安全地直接减去的原因是，每个跳过的年份恰好对应于一场错过的比赛，并且该问题保证不存在重复，因此不需要进行过量计算校正。 

### 为什么它有效

 计数过程基于对整个区间进行划分`[y1, y2]`分为两个不相交的集合：发生比赛的年份和不发生比赛的年份。 间隔中的每一年要么在跳过列表中，要么不在跳过列表中。 由于我们从间隔中的完整年份开始，并精确删除那些标记为跳过且位于间隔内的年份，因此每个有效的比赛年份都将被精确计算一次，而每个无效年份将被精确删除一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        parts = input().split()
        y1 = int(parts[0])

        # next line: n followed by n skipped years
        parts = input().split()
        n = int(parts[0])
        skipped = list(map(int, parts[1:]))

        y2 = int(input())

        total = y2 - y1 + 1

        for s in skipped:
            if y1 <= s <= y2:
                total -= 1

        print(total)

if __name__ == "__main__":
    solve()
```实现直接遵循算法。 唯一值得注意的细节是输入解析：因为跳过的年份与`n`，我们读取整行并将其拆分。 这避免了每个测试用例的可变长度输入的问题。 

计算使用简单的累加器`total`，初始化为完整间隔大小，并仅针对相关跳过年份递减。

 ## 边缘情况

 一种边缘情况是当`y1 == y2`，意味着该时间间隔恰好包含一年。 该算法将总计设置为 1，然后仅当该年份出现在跳过列表中时才减去 1。 既然问题保证了`y2`不是跳过的年份，结果将始终保持 1。例如，`y1 = y2 = 2020`任何不包含 2020 的跳过列表都会产生输出 1，如果跳过 2020，它将与约束相矛盾。 

另一个边缘情况是所有跳过的年份都位于查询间隔之外。 在这种情况下，不会发生减法，结果仍然是完整的间隔长度。 过滤条件`y1 <= s <= y2`确保完全忽略这些值。 

最后一个微妙的情况是，跳过的年份很密集，但仍然受`n ≤ 100`。 即使全部都躺在里面`[y1, y2]`，算法正确地减去`n`从总数中生成正确的剩余计数，无需任何排序或设置结构。
