 ## 解决方案
 ## 问题理解

 我们得到一排索引从 1 到 m 的房屋，我们必须将 n 个人放入不同的房屋中。 仅当两个人占据相邻的房屋索引时才被视为邻居。 每个人对总分有两种可能的贡献：如果他们最终至少有一个邻居，他们贡献 ai，否则他们贡献 bi。 

任务是为所有人选择职位，使他们的贡献总和最大化。 问题的结构实际上并不是关于单线之外的几何；而是关于几何。 重要的是我们如何将人们分为连续的街区，因为相邻性仅由连续占用的房屋决定。 

这些约束立即排除了任何组合分配方法。 测试中 n 最多为 5×10^5，m 最多为 10^9，我们无法模拟布局或尝试排列。 任何解决方案都必须将问题简化为对人员的线性或近线性扫描，理想情况下是 O(n log n) 或 O(n)。 

一个微妙的点是 m 很大，但除了提供足够的空白空间来分隔组之外，其他无关紧要。 我们永远不会被迫填满所有的房子，所以重要的是我们如何将 n 个人分成沿线某处放置的连续部分。 

一个天真的错误是认为我们必须选择精确的宫位。 这导致了 DP 对 m 的棘手放置。 相反，实际的结构仅取决于谁最终相邻，而不取决于他们放置的位置。 

重要的边缘情况：

 如果 n = m，每个人都被迫进入一个完全填满的段，因此每个人都有邻居，除了可能在末端的情况。 例如，当 n = 2 且 m = 2 时，无论偏好如何，两者都是邻居，因此我们必须对所有对象取 ai + aj。 

如果 m 与 n 相比非常大，我们可以隔离每个人，这意味着所有贡献都是 bi。 例如，n = 3，m = 100 给出总和 bi 的基线答案，然后如果有益，我们有选择地创建邻接组。 

一个关键的张力是决定何时值得让某人成为邻居（用 ai 而不是 bi），因为这会迫使结构性分组，而这也可能影响其他人。 

## 方法

 我们从暴力的角度开始。 假设我们尝试明确地将人员分配到房屋并评估所有有效的安置。 即使我们忽略确切的位置并只考虑邻接模式，我们仍然会选择哪些对成为一条线上的邻居。 这相当于将 n 个人分成段，其中长度为 k 的每个段为该段的所有成员贡献 ai，长度为 1 的段贡献 bi。 

所以问题就变成了选择人员序列的分割。 暴力 DP 会将 dp[i] 视为前 i 个人的最佳值，并尝试所有先前的切点。 这会导致 O(n^2) 次转换，这对于 n 达到 5×10^5 来说是不可能的。 

关键的见解是将每个人的选择转化为相对于孤立的收益。 如果每个人都是孤立的，则基本分数为 sum bi。 如果我们将一个人放入规模至少为 2 的群体中，我们将获得 ai - bi。 然而，形成一个群体也需要至少一个邻接边，并且邻接边是在两个人之间共享的。 每个相邻对有效地“激活”两个端点，因为它们具有至少一个邻居。 

这重新定义了问题：我们沿着 n 个人的一条线选择一组邻接边。 每个选定的边 (i, i+1) 意味着 i 和 i+1 都成为非单组件的一部分。 任何大小为 k 的连通分量为所有 k 个成员贡献 sum(ai)，而孤立的顶点贡献 bi。 

现在该结构变成了经典的一维动态规划，其中的决定是是否开始一个段或扩展它，但我们可以进一步简化：对于每个位置，我们决定它是参与一个组还是保持隔离，并且组是大小至少为 2 的连续间隔。

我们定义一个 DP，从左到右扫描，维护我们当前是否在一个组内。 转换仅取决于本地决策，因为一旦组开始，扩展它总是对称地影响两个端点。 

最后的简化是，最佳解决方案是贪婪地形成群体，只要将相邻的人配对的收益总体上是正的。 我们评估连接 i 和 i+1 是否会产生净收益：

 (ai + a(i+1)) - (bi + b(i+1)) 与将两者隔离相比。 

因此，每个邻接边都有一个权重 wi = (ai - bi) + (a(i+1) - b(i+1))。 我们想要选择一组不重叠的边，这样每个选定的边都会给 wi 带来好处，但是选择相邻的边会重叠人员并合并组件。 这简化为路径上经典的最大权重匹配，可以通过 O(n) 中的 DP 来解决。 

让 dp[i] 成为考虑第 i 个人的最佳答案。 然后：

 dp[i] = max(dp[i-1], dp[i-2] + wi-1)

 这正是一条线上的加权匹配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解分段 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 路径DP/加权匹配| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算等于所有 bi 总和的基线分数，将每个人视为孤立的。 这表示根本没有邻接的配置。 
2. 对于每个相邻对 i 和 i+1，计算连接它们的额外收益。 如果两者都成为一个组的一部分，我们将 bi + b(i+1) 替换为 ai + a(i+1)，因此增益为 (ai + a(i+1)) - (bi + b(i+1))。 
3. 定义一个动态编程数组 dp，其中 dp[i] 表示仅使用前 i 个人即可实现的最大额外增益，考虑我们是形成邻接边还是将它们隔离。 
4. 初始化dp[0] = 0，dp[1] = 0，因为单个人无法获得任何邻接收益。 
5. 对于从 2 到 n 的每个 i，决定是不形成以 i 结尾的组（这会保持 dp[i] = dp[i-1]），还是形成具有 i-1 和 i 的组（这会贡献边缘增益并跳过 i-2 以避免重叠），从而给出 dp[i-2] + 增益（i-1）。 
6. 答案是bi 加dp[n] 的基线总和。 

工作原理：最终排列中的每个连接组件都对应于一组边，这些边在一条线上形成不相交的路径。 每个选定的边缘恰好将两个相邻的人激活为“邻居存在”状态，并且任何最佳配置都可以分解为不重叠的边缘而不失一般性。 DP 通过防止边缘重叠来强制实施这种结构，确保每个人都被一致地视为孤立的或恰好是一个邻接关系的一部分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = []
    b = []
    base = 0

    for _ in range(n):
        ai, bi = map(int, input().split())
        a.append(ai)
        b.append(bi)
        base += bi

    if n == 1:
        print(base)
        return

    gain = [(a[i] - b[i]) + (a[i+1] - b[i+1]) for i in range(n - 1)]

    dp_prev2 = 0
    dp_prev1 = max(0, gain[0])

    for i in range(2, n):
        dp_cur = max(dp_prev1, dp_prev2 + gain[i - 1])
        dp_prev2, dp_prev1 = dp_prev1, dp_cur

    extra = dp_prev1
    print(base + extra)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```该实现将解决方案分为基线部分和增益最大化部分。 基线总和确保每个人都从隔离配置开始。 然后 DP 只处理邻接改进。 

阵列增益将每个可能的边缘压缩为单个值，表示使邻接处于活动状态的好处。 滚动 DP 变量 dp_prev2 和 dp_prev1 避免分配 O(n) 数组，考虑到约束，这是必要的。 

一个微妙的点是单独处理 n = 1，因为不存在邻接，否则 DP 公式将访问无效索引。

 ## 边缘情况

 一种边缘情况是 n = 1。算法正确返回基线总和 bi，因为不存在邻接，并且 DP 被完全绕过。 

另一个边缘情况是所有收益均为负值。 在这种情况下，DP 永远不会选择任何边缘，因为 dp[i-2] + 增益总是比跳过更糟糕。 输出仍然是 bi 的总和，符合没有分组是有益的解释。 

最后的边缘情况是高值和低值交替，其中最佳配对不是连续的而是选择性的。 DP 强制执行非重叠边缘，因此如果能产生更高的总增益，它自然会选择所有其他边缘，而不违反邻接约束。
