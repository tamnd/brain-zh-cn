 ## 解决方案
 ## 问题理解

 该问题要求能在矩形墙上切出最大的矩形窗户。 墙有宽度`w`和身高`h`，并且窗口必须至少保持`d`距墙每一个边缘的单位。 所需间隙独立适用于所有四个侧面。 我们需要输出最大可能的窗口面积，或者`0`当所需的间隙没有留下窗户的空间时。 原竞赛指定`w, h < 1000`和`d < 100`，时间限制为一秒，内存为 256 MB。 

几何形状立即减少可用宽度`d`在左边和`d`在右边，所以最大可能的窗口宽度是`w - 2d`。 同样的推理给出了最大高度`h - 2d`。 如果任一值为非正值，则无法容纳具有正面积的窗口。 否则，最大的矩形将使用两个可用尺寸。 

小界限意味着即使`O(w h)`在最坏的情况下，枚举只会检查大约一百万对，因为`w`和`h`在下面`1000`。 这根本无法与`10^5`-自动排除二次算法的规模约束。 然而，这个问题包含足够的几何结构，不需要枚举：可以通过恒定数量的算术运算来计算答案。 

有两种边界情况通常会导致错误的实现。 首先，间隙会消耗整个维度。 例如，使用输入`30 20 12`，可用宽度为`30 - 24 = 6`，而可用高度是`20 - 24 = -4`，所以正确的输出是`0`。 粗心的实现将两个值相乘而不检查它们会产生`-24`，它不能代表窗口区域。 

其次，间隙可以大于两个尺寸的一半。 为了`40 25 50`，可用尺寸为`-60`和`-75`，所以答案又是`0`。 仅检查是否`w - 2d`为正值是不够的，因为高度也必须足够大。 官方样本包括这两种不可能的情况。 

另一个边界是精确拟合的情况。 如果`w = 2d`或者`h = 2d`，对应的窗口尺寸为零。 面积为零的矩形不是可用的窗口，所以答案仍然是`0`。 例如，`10 20 5`叶子宽度`0`，给出输出`0`。 

## 方法

 直接的暴力方法可以枚举每个整数宽度`1`通过`w - 1`和每个整数高度`1`通过`h - 1`。 对于每一对，我们将检查矩形是否可以容纳，同时在每边留下所需的间隙，并保留最大的有效区域。 该方法是正确的，因为考虑了每个候选维度对，因此最终必须找到最佳有效对。 

和`w, h < 1000`，该枚举最多执行大约`(w - 1)(h - 1)`，低于一百万维对。 因此，与许多 Codeforces 问题不同，在这些限制下，暴力破解实际上并不是灾难性的。 尽管如此，它正在解决一个比必要的更普遍的问题，而且它`O(w h)`工作是可以避免的。 

关键的观察是，扩大有效窗口永远不会使其面积变小。 一旦保留了所需的边框，窗口就可以占据每个剩余的宽度单位和每个剩余的高度单位。 水平和垂直约束之间没有相互作用，因此可以独立确定最佳宽度和最佳高度。 

墙给了`w`水平单位。 左边框消耗`d`，右边界消耗另一个`d`，离开`w - 2d`。 垂直方向上，顶部和底部边框同样离开`h - 2d`。 如果两个数量都是正数，则它们的乘积是最大的可能面积。 如果其中一个为非正值，则不存在正区域窗口。 

蛮力之所以有效，是因为它最终测试了最大维度，但未能利用每个较小的有效维度都受较大维度支配的事实。 观察到两个维度都可以简单地推至最大值，从而将整个问题简化为常数时间算术。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(宽·高) | O(1) | O(1) | 在给定范围内接受，但没有必要 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取墙宽`w`，墙高`h`，以及所需的边界间隙`d`。 
2. 计算最大可能的窗口宽度为`w - 2d`。 减法是通过`2d`因为窗户必须离开`d`左侧和右侧都有单位。 
3. 计算最大可能的窗口高度为`h - 2d`。 同样的论点也适用于顶面和底面。 
4. 检查任一可用维度是否小于或等于零。 如果是，则输出`0`，因为非正宽度或高度不能形成正面积矩形窗口。 
5. 否则，将可用宽度和高度相乘并输出乘积。 选择任一方向的最大可用值不会损害该区域，因此这两个维度一起给出了最大可能的窗口。 

### 为什么它有效

 考虑任何有效的窗口。 因为它至少必须离开`d`其周长和每个墙边之间的单位，其宽度永远不能超过`w - 2d`，并且它的高度永远不能超过`h - 2d`。 当两个数量均为正数时，通过在每一侧放置所需的间隙来拟合具有完全相同尺寸的窗口，因此有效窗口不能具有更大的宽度或高度。 由于面积是宽度和高度的乘积，`(w - 2d)(h - 2d)`是最大可能的面积。 当任一维度为非正数时，没有正面积矩形可以满足边框要求，因此返回零是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

w, h, d = map(int, input().split())

window_w = w - 2 * d
window_h = h - 2 * d

if window_w <= 0 or window_h <= 0:
    print(0)
else:
    print(window_w * window_h)
```第一行从唯一的输入行读取三个整数。 没有要循环的测试用例，因此程序只执行一次计算。 

接下来的两个作业将几何直接转换为算术。`2 * d`被使用而不是`d`因为所需的边框出现在每个尺寸的相对两侧。 

条件使用`<= 0`， 不是`< 0`。 当剩余尺寸恰好为零时，所得矩形的面积为零，并且不是有效的正面积窗口。 

Python 整数不会溢出，并且给定的边界无论如何都会使结果区域非常小。 该解决方案还仅使用恒定量的内存。 

## 工作示例

 对于示例 1，输入为`40 25 5`。 所需间隙消除`5`每一侧的单位。

 | 计算尺寸 | 40 | 40 25 | 25 5 | 30| 15 | 15 |
 | 检查可行性 | 40 | 40 25 | 25 5 | 30| 15 | 15 有效 |
 | 计算面积| 40 | 40 25 | 25 5 | 30| 15 | 15 450 | 450

 剩下的两个维度都是正的，所以整个`30 × 15`室内可以使用。 输出是`450`，匹配样本。 

对于示例 2，请考虑`30 20 12`。 

| 步骤|`w`|`h`|`d`|`window_w`|`window_h`| 结果 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 读取输入| 30| 20 | 12 | 12 | | |

 水平尺寸仍然有空间，但垂直尺寸没有。 单个无效维度足以使整个窗口变得不可能，因此算法返回`0`。 

这些痕迹说明了为什么在乘以维度之前必须检查可行性。 当其中一个维度为非正数时，乘法本身没有几何意义。

## 测试用例```python
import sys
import io

def solve():
    input = sys.stdin.readline
    w, h, d = map(int, input().split())

    window_w = w - 2 * d
    window_h = h - 2 * d

    if window_w <= 0 or window_h <= 0:
        print(0)
    else:
        print(window_w * window_h)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

# Provided samples
assert run("40 25 5\n") == "450\n", "sample 1"
assert run("30 20 12\n") == "0\n", "sample 2"
assert run("40 25 50\n") == "0\n", "sample 3"
assert run("999 888 7\n") == "860890\n", "sample 4"

# Minimum-size dimensions
assert run("1 1 1\n") == "0\n", "no room for a window"

# Exact-fit boundary
assert run("10 20 5\n") == "0\n", "zero remaining width"

# All dimensions comfortably fit
assert run("100 100 10\n") == "6400\n", "all-equal wall dimensions"

# Maximum-size input values
assert run("999 999 99\n") == "641601\n", "maximum bounds"

 ## 边缘情况

 对于`30 20 12`，算法计算`window_w = 6`和`window_h = -4`。 自从`window_h <= 0`，它立即输出`0`。 这可以防止负产品被误认为是区域。 

为了`40 25 50`，可用尺寸为`-60`和`-75`。 相同的可行性检查返回`0`。 这捕获了假设输入总是留有足够空间的实现，因为`w`和`h`他们自己都是积极的。 

对于精确配合的情况`10 20 5`，可用宽度为`10 - 2(5) = 0`。 该算法将零视为不可能并输出`0`，而不是接受退化矩形。 

对于正常的有效情况，例如`40 25 5`，可用尺寸为`30`和`15`。 两者都是正数，因此算法将它们相乘并获得`450`。 计算使用了允许属于窗户的墙壁的每个部分，这证明没有更小的候选者可以是最佳的。
