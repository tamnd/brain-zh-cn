 ## 解决方案
 ## 问题理解

 遥控器有十位数字按钮，以及频道向上和频道向下。 有些数字按钮坏了，而两个通道按钮一直可以用。 电视的频道编号为 0 到 999。 

目标通道介于 1 和 999 之间。Orooji 博士可以首先键入十进制表示仅使用工作数字的任何通道编号。 之后，他可以根据需要多次按频道向上或频道向下。 所需的输出是达到目标所需的通道向上或通道向下按压的最少次数。 用于键入初始频道的数字按键次数对答案没有贡献。 

输入给出了损坏的数字的数量，后跟这些数字，然后给出了所需的通道。 至少有一位有效数字，因为十位数字中至多有九位已损坏。 由于通道范围仅从 0 到 999，因此可以直接键入正好有 1000 个可能的通道。 官方限制为 1 秒和 256 MB，因此直接检查这 1000 个通道的方法速度相当快。 

中心边缘情况是通道 0。尽管请求的通道至少为 1，但 Orooji 博士可以输入通道 0 作为他的起始通道。 例如，```
1 1
2
```有输出`2`，因为数字 1 已损坏，所以通道 0 是最近的直接可选择通道，并且两次通道向上按键可到达通道 2。粗心的实现仅检查通道 1 至 999 将错过这种可能性。 

另一种极端情况是目标本身可以被输入。 例如，```
1 0
50
```有输出`0`，因为 50 仅使用工作数字。 总是添加至少一次通道按钮按下的实现是错误的。 

另一个边界是通道 999。遥控器无法移动到 999 以上，因此在该边界之外没有有效的直接键入通道。 例如，```
9 1 2 3 4 5 6 7 8 9
999
```仅留下数字 0 起作用。 唯一可直接输入的通道是 0，所以答案是`999`。 意外地将 1000 视为可能通道的搜索可能会产生无效的较小距离。 

频道中重复的数字也很重要，因为数字每次出现都必须起作用。 如果数字7被破坏，那么7、77和707都无法使用。 例如，```
1 7
777
```无法直接键入目标，即使目标仅由一位不同的数字组成。 必须通过检查各个十进制数字来找到最佳可用的起始通道。 

## 方法

 一个简单的解决方案是尝试从 0 到 999 的每个通道。对于每个候选通道，将其转换为十进制表示法并检查每个数字是否有效。 如果候选可用，则达到目标所需的通道按钮按下次数就是候选与目标之间的绝对差。 取这些值中的最小值即可得出答案。 

这种蛮力方法已经足够快了。 候选通道只有1000个，每个通道最多包含三位小数。 最坏的情况最多执行约 3000 位数字检查，然后进行恒定时间距离计算。 不需要更复杂的数据结构或动态编程技术。 

暴力破解之所以有效，是因为通道范围很小。 如果通道的范围达到类似 (10^9) 的范围，则检查每个可能的通道将需要多达 10 亿个候选通道，并且完全不适合 1 秒的限制。 在这里，从 0 到 999 的固定范围改变了情况：穷举枚举实际上是一项持续的工作。 

关键的观察是每个可能的第一通道都是独立的。 如果候选频道是可打字的，那么从该频道到达目标的最便宜的方式完全取决于它们的数字距离。 因此，我们不需要模拟按钮按下或搜索路径。 我们只需要找到距目标绝对距离最小的可用通道。 

这给出了以下比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(1000 × 3) = O(1) | O(1) | O(1) | 已接受 |
 | 最佳| O(1000 × 3) = O(1) | O(1) | O(1) | 已接受 |

 对于这个问题，暴力枚举也是最佳的实用方法。 区别在于，重要的优化是认识到搜索空间只有 1000 个通道，而不是试图发明更复杂的算法。 

## 算法演练

 1. 读取一组损坏的数字并将其存储在布尔结构中。 对于每个数字，该结构会在恒定时间内告诉我们该数字是否可以被按下。 
2. 读取目标通道。 
3. 将答案初始化为大于任何可能距离的值，例如 1000。两个通道之间在 0 到 999 范围内的最大可能距离是 999。 
4. 枚举从 0 到 999 的每个候选通道。我们包括两个端点，因为通道 0 是合法的起始通道，而通道 999 是最大可能的通道。 
5. 将候选值转换为十进制字符串并检查每个数字。 如果有任何数字被破坏，则丢弃该候选者。 整个号码都无法使用，因为即使输入一个损坏的数字也是不可能的。 
6. 如果每个数字都有效，则计算`abs(candidate - target)`。 这正是从候选移动到目标所需的频道向上或频道向下按下的次数。 
7. 如果当前答案更小，则用该距离替换当前答案。 
8. 在检查完所有 1000 名考生后，打印最小距离。 

正确性来自一个简单的不变量：在将每个候选通道处理到某个值（x）之后，`answer`是处理范围内所有可用通道中距目标的最小通道按钮距离。 当输入所需的每个数字都有效时，就会准确地考虑候选者，因此不会错误地拒绝可用的起始通道。 它到目标的距离恰好是所需的通道向上或通道向下按压的次数，因此取最小值考虑了该候选者的最佳成本。 处理完通道 999 后，已考虑了每个可能的起始通道，因此存储的最小值是全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, *broken_digits = map(int, input().split())
target = int(input())

broken = [False] * 10
for d in broken_digits:
    broken[d] = True

answer = 1000

for channel in range(1000):
    if all(not broken[int(d)] for d in str(channel)):
        answer = min(answer, abs(channel - target))

print(answer)
```第一个输入行被解包为`n`和破碎的数字。 的价值`n`读取后不需要，因为输入已经在行上给出了那么多的数字，但读取它可以使输入结构保持明确。 

这`broken`array 提供常量时间成员资格检查。`broken[d]`当数字为真时`d`无法按下。 

循环使用`range(1000)`，它生成从 0 到 999 的每个通道。该上限包含在问题中，因此使用`range(999)`排除通道 999 会引入差一错误。 

对于每个候选人来说，`str(channel)`公开必须键入的所有十进制数字。 这也能正确处理通道 0，因为`str(0)`是`"0"`。 只有当每个数字都通过了破损按钮测试时，候选人才会被接受。 

距离是`abs(channel - target)`。 如果候选值低于目标，则相当于按频道向上。 如果高于目标，则对应于通道向下。 由于每个通道两个方向的成本为一次印刷机，因此绝对差异是最小的。 

Python整数在这里不会溢出，并且有史以来存储的最大值`answer`只有1000，总的工作量很小，很普通`sys.stdin.readline`对于输入大小来说已经绰绰有余了。

 ## 边缘情况

 当通道 0 是最佳起点时，算法会处理它，因为枚举从 0 而不是 1 开始。对于输入```
1 1
2
```数字 1 被破坏，因此通道 1 和包含 1 的每个通道都被拒绝。 通道 0 有效，与目标 2 的距离为 2。算法打印`2`。 

当目标可以直接输入时，算法会像其他候选者一样评估目标。 为了```
1 0
1
```数字 0 已损坏，但数字 1 可用。 候选通道 1 通过数字检查，并且`abs(1 - 1)`是 0. 答案是`0`，无需按下频道按钮。 

当几乎每个数字都被破坏时，搜索仍然有效，因为它不假设特定数量的数字可用。 为了```
9 1 2 3 4 5 6 7 8 9
999
```只有数字 0 有效。 在 0 到 999 的所有通道中，只能键入通道 0，因此距离为`999`。 该算法准确地找到该候选者并输出`999`。 

重复的数字是独立检查的，因为十进制表示是逐个字符扫描的。 和```
1 7
777
```目标的每个字符都是破7，所以777被拒绝。 唯一可用的通道不包含 7，而通道 0 是最近的此类通道，距离为 777。这可以防止仅检查候选数字是否包含明显的损坏数字一次而不实际验证每个数字位置的常见错误。 

最后，通过迭代包含上端点`range(1000)`。 为了```
1 9
999
```目标本身无法输入，因为 9 被破坏了。 通道 998 可用，并且正好比目标低一个通道，因此算法返回`1`。 从候选范围中排除 999 不会改变这个特定的答案，但排除端点通常会使枚举不完整，并且当 999 本身是最佳直接键入通道时可能会失败。
