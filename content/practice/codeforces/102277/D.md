 ## 解决方案
 ## 问题理解

 我们在笛卡尔平面上有一个圆和一个轴对齐的正方形。 圆由其中心描述`(x, y)`和半径`r`。 正方形由其左下角描述`(tx, ty)`和边长`s`，所以它的对角是`(tx + s, ty + s)`。 任务是对它们的几何关系进行分类。 我们打印`0`当它们不相交时，`1`当它们的共同部分恰好由一个点组成时，并且`2`当它们与正区域重叠时。 官方的限制只有`1000`坐标和尺寸的大小，时间限制为 1 秒，内存为 256 MB。 

数值范围很小，但它们并不表明有用的模拟。 对象包含无限多个点，甚至迭代边界框中的每个整数坐标也不是有效的几何算法，因为切点可以具有非整数坐标。 干净的解决方案应该使用恒定数量的算术运算，并完全避免浮点几何。 

在几种边界情况下，仅检查某个角是否位于另一个对象内部的实现可能会失败。 例如，```
0 0 5
5 0 6
```有输出`1`。 广场开始于`(5, 0)`，距离圆心正好五个单位，因此两个物体在`(5, 0)`。 严格的`< r`测试会错误地报告`0`，因为接触点位于圆上而不是圆内。 

第二种情况是完全在正方形内的圆：```
0 0 1
-5 -5 10
```正确的输出是`0`。 尽管两个几何区域具有包容性，但圆根本不与正方形的边界相交。 假设“一个对象位于另一个对象内部，因此它们重叠”的方法会将包含与边界相交混淆。 所需的分类是关于圆形和方形是否有公共区域或单个公共点，因此对于圆盘和方形区域，这种情况实际上具有正面积交集，并且必须分类为`2`。 这说明了为什么对象的确切含义很重要：圆圈表示其填充的内部作为被比较区域的一部分。 

一个更有用的边缘情况是反向包含：```
0 0 10
-1 -1 2
```正确的输出是`2`。 整个正方形位于圆内，因此它们的交点面积为正。 仅检查圆极值点是否位于正方形内部将完全忽略这一点。 

避免所有这些特殊情况的最简洁方法是将问题简化为一个量：从圆心到正方形任意点的最小距离。 

## 方法

 直接的几何强力可以枚举正方形的四个角和圆的四个基点，然后对这些候选点中的任何一个是否严格位于另一个形状内部或恰好位于另一个形状上进行分类。 这是一个恒定大小的搜索，通过适当的凸性参数可以解决问题。 它执行四次从角到圆的检查和四次从圆极点到正方形的检查，因此最坏的情况是八次距离或包含检查，加上相应的算术。 该方法被渐近地接受，因为该问题只有一个测试用例，但很容易因忘记包含配置或边界情况而使其不完整。 

更好的观察是我们根本不需要搜索交点。 对于固定的圆心，找到最接近该圆心的正方形点。 如果中心在水平方向上位于正方形之外，则最近的点必须使用相应的垂直边。 如果中心在水平方向上位于正方形内，则其最近点具有相同的`x`协调。 同样的推理独立地适用于`y`协调。 

这通过独立地夹紧每个坐标来给出最接近的方形点。 如果中心有坐标`x`，正方形的跨度`[tx, tx+s]`，最接近的有效平方`x`坐标是```
min(max(x, tx), tx+s)
```类似地对于`y`。 

一旦知道了最近的点，几何图形就变成了简单的距离比较。 让`d`是从圆心到该点的距离。 如果`d < r`，圆到达面积为正的正方形。 如果`d = r`，圆与正方形恰好在一点处相切。 如果`d > r`，圆和正方形不相交，除非正方形完全在圆内。 后一种情况已经涵盖`d < r`，因为圆心要么在正方形内部，要么足够接近正方形边界，使得圆包含正方形的一部分。 

重要的简化是可以使用平方距离进行比较。 既然两者`d`和`r`是非负的，比较`d²`和`r²`给出完全相同的结果，并避免平方根和浮点精度问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 角点和极值点检查 | O(1) | O(1) | O(1) | O(1) | 已接受，但案例较多 |
 | 夹紧最近点| O(1) | O(1) | O(1) | O(1) | 已接受，优先 |

 ## 算法演练

 1.读取圆心`(x, y)`， 半径`r`，以及正方形的左下角`(tx, ty)`和边长`s`。 
2. 计算正方形的右边界和上边界：`right = tx + s`和`top = ty + s`。 平方正是笛卡尔积`[tx, right] × [ty, top]`。 
3. 夹住圆心`x`坐标到正方形的水平间隔。 计算`px = min(max(x, tx), right)`。 如果`x`已经在区间内，`px`等于`x`。 如果`x`是在左边，`px`变成`tx`，如果`x`是在右边，`px`变成`right`。 
4. 执行相同的操作`y`，得到`py = min(max(y, ty), top)`。 重点`(px, py)`是正方形中距离圆心最近的点。 
5. 计算距离的平方`(x, y)`到`(px, py)`作为`dist2 = (x - px)^2 + (y - py)^2`。 将其与`r^2`。 
6. 打印`2`如果`dist2 < r^2`，因为圆延伸到正方形，并且交点的面积为正。 打印`1`如果`dist2 == r^2`，因为最近的正方形点恰好位于圆上。 否则打印`0`，因为正方形的每个点到圆心的距离都比半径远。 

该算法背后的不变量是`(px, py)`始终是正方形最接近圆心的点。 正方形的每个点到中心的距离至少与该点一样远。 因此，如果最近的点位于圆之外，则整个正方形都在圆之外。 如果它严格位于圆内，则该点周围的一个小邻域也位于圆内，从而产生正面积交集。 如果它恰好位于圆上，则正方形和圆在最近的点处相交，并且不能相互穿透，从而形成单点接触。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x, y, r = map(int, input().split())
    tx, ty, s = map(int, input().split())

    right = tx + s
    top = ty + s

    px = min(max(x, tx), right)
    py = min(max(y, ty), top)

    dx = x - px
    dy = y - py

    dist2 = dx * dx + dy * dy
    r2 = r * r

    if dist2 < r2:
        print(2)
    elif dist2 == r2:
        print(1)
    else:
        print(0)

if __name__ == "__main__":
    solve()
```前两行输入与算法中完全相同地描述了两个几何对象。 我们立即计算正方形的右边界和上边界，因此后续表达式可以将正方形视为两个封闭的坐标区间。 

两人`min(max(...))`表达式实现坐标夹紧。 Python 的整数运算在这里特别方便，因为每个输入都是整数，并且最大平方差很容易在 Python 的任意精度整数范围内。 

减法是在钳位后有意进行的。 这给出了从圆心到正方形的最短向量的水平和垂直分量。 平方和相加给出最小距离的平方。 

严格比较和非严格比较都是必要的。`<`表示最近的正方形点在圆内，而`==`代表精确相切。 将相等情况替换为`<=`会错误地将每个切线配置分类为重叠。 

不取平方根，因此在相切情况下不存在浮点误差，例如距离恰好为`5`与半径相比`5`。

 ## 边缘情况

 第一个微妙的情况是精确相切。 和```
0 0 5
5 0 1
```正方形最接近中心的点是`(5, 0)`。 距离的平方为`25`，正好等于`r² = 25`，所以算法打印`1`。 没有单独的相等情况的严格内部测试将错误地打印`0`。 

第二种情况是圆心位于正方形内部。 为了```
0 0 1
-5 -5 10
```夹紧使中心保持不变，所以`(px, py) = (0, 0)`。 最小平方距离是`0`，小于`1`。 算法打印`2`，正确认识到圆形和正方形有正面积交点。 

第三种情况是正方形完全位于圆内：```
0 0 10
-1 -1 2
```同样，圆心位于正方形内部，因此距中心最近的正方形点就是中心本身，最小平方距离为`0`。 自从`0 < 100`，结果是`2`。 这种情况很有用，因为仅检查正方形与圆的边界点会完全错过交点。 

第四种情况是对角分离：```
0 0 5
5 5 1
```最近的点是`(5, 5)`，给出平方距离`25 + 25 = 50`。 自从`50 > 25`，结果是`0`。 比较平方距离也可以处理对角线，而无需引入平方根。 

第五种情况是大坐标边界配置：```
1000 1000 1000
-999 -999 1000
```正方形结束于`(1, 1)`，这是最接近的点`(1000, 1000)`。 距离的平方为`999² + 999²`，大于`1000²`，所以算法打印`0`。 这证实了坐标边界不需要任何特殊处理。
