[CF 102277I - 球队衬衫/球衣](https://codeforces.com/problemset/problem/102277/I)

 **标签：** -
 **求解时间：** 2m 1s

 ## 解决方案
 ## 问题理解

 Travis 最多有 25 个朋友，每个朋友都选择了从 1 到 99 的球衣号码。Travis 可以为自己选择一个额外的球衣号码，也是从 1 到 99。他想知道自己的号码选择是否可以连接一些可用的球衣号码并准确地获得他最喜欢的整数。 

所选球衣号码的顺序是任意的。 球衣号码必须作为一个整体使用，因此如果有人拥有球衣 75，特拉维斯可能会使用`75`，但不能仅使用`7`或仅`5`。 朋友的球衣可以省略，特拉维斯自己的球衣也可以省略。 输出是`1`如果存在特拉维斯数的选择，使得最喜欢的整数可构造，并且`0`否则。 官方声明给出`t < 1,000,000,000`,`n <= 25`，以及 1 到 99 范围内的球衣号码。 

的小值`n`可能会建议指数搜索，但更严格的限制是对最喜欢的整数。 由于它低于 10 亿，因此最多有 9 位小数。 每件球衣贡献一位或两位数字。 这意味着目标只有极少数可能的方法将其十进制表示形式分割成有效的球衣大小的部分。 与可能的分割数量成比例的解决方案很容易足够快，而枚举任意子集和最多 25 个朋友的排列则成本太高。 

第一个边缘情况是由单个数字组成的目标。 例如，与```
7
1
24
```答案是`1`，因为特拉维斯可以简单地选择球衣`7`并单独使用它。 假设至少一个朋友的球衣必须参与的解决方案将错误地拒绝这种情况。 

内部零需要小心。 例如，```
101
1
10
```有答案`1`，因为目标可以拆分为`10 | 1`，与现有球衣`10`接下来是特拉维斯选择的球衣`1`。 独立处理每个数字会错误地将零视为球衣号码，而将其拆分为`1 | 01`也将无效，因为球衣`01`不存在。 

重复的球衣号码是错误的另一个来源。 例如，```
2222
3
2 2 2
```有答案`1`。 目标需要四份球衣`2`，三个是朋友提供的，Travis可以选择`2`他自己。 忘记多重性的基于集合的实现将失去这种区别。 

最后，如果目标不能划分为那些完整的值，那么仅仅拥有正确的值是不够的。 例如，```
715
1
75
```有答案`0`。 可用的朋友球衣贡献`75`，但目标需要`7 | 15`或者`71 | 5`，并且使用单个朋友加上一件新选择的球衣都不能提供分解。 

## 方法

 直接的暴力方法会尝试选择朋友的子集，选择该子集的排序，决定是否使用特拉维斯的球衣，选择他的球衣号码，连接所有内容，并将结果与目标进行比较。 这是正确的，因为每一个法律解释都由某种这样的选择来代表。 问题在于可能性的数量。 为了`n = 25`，有序子集的数量为

 25!\sum_{j=0}^{25}\frac{1}{j!},
 ]

 这大约是`e * 25!`，或关于`4.2 * 10^25`。 尝试多达 99 种 Travis 球衣选择，推动这一目标的实现`4.2 * 10^27`候选结构。 这远远超出了两秒程序所能检查的数量级。 

关键的观察是我们实际上并不需要首先选择朋友。 目标本身决定了球衣号码的可能顺序。 由于每件球衣的数字都在 1 到 99 之间，因此每件目标都必须恰好包含一位或两位数字。 对于一个目标`L`的数字，只有`L - 1`我们可以削减或不削减的职位。 因此最多有

 [
 2^{L-1} \le 2^8 = 256
 ]

 可能的分区。 

对于每个分区，我们获得一个一位数或两位数的序列。 我们可以计算出该分区需要多少份球衣号码。 朋友们提供了一些多组球衣号码。 当朋友之间每个所需的副本都可用时，分区是可行的，除了 Travis 最多可以提供一个缺失的副本。 

Travis 没有必要尝试所有 99 种可能的选择。 如果某个分区缺少一个球衣号码，特拉维斯只需选择该号码即可。 如果缺少两份或更多副本，一件球衣无法修复分区。 如果没有遗漏任何内容，特拉维斯可以选择任何有效的球衣号码并且不使用它。 

蛮力方法之所以有效，是因为它明确地搜索所有可能的构造，但当它将 25 个朋友视为搜索空间时，就会失败。 目标最多有九个数字的观察结果完全改变了搜索空间。 我们没有探索朋友的排列，而是列举了目标本身最多 256 种可以划分为合法球衣号码的方式。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(99 * e * n!)`|`O(n)`| 太慢了 |
 | 最佳 |`O(2^8 * n)`|`O(1)`除了输入存储之外| 已接受 |

 ## 算法演练

 1. 将最喜欢的整数转换为其十进制字符串表示形式。 我们直接处理数字，因为有效的构造是球衣号码的串联，因此每个有效的构造都对应于该字符串的一个分区。 
2. 计算从 1 到 99 的每个球衣号码在朋友中出现了多少次。 频率数组很方便，因为整个值范围仅包含 99 种可能性。 
3. 枚举每个子集`L - 1`连续目标数字之间的间隙。 选定的差距意味着当前的球衣号码到此结束。 未选择的间隙意味着下一个数字属于相同的球衣号码。 
4. 对于每个分区，从左到右扫描目标并形成相应的一位数或两位数棋子。 拒绝等于 0 的作品，因为球衣号码从 1 开始。同时拒绝以 0 开头的两位数作品，因为给出的球衣号码没有前导零。 
5. 计算每个结果球衣号码所需出现的次数。 将这些要求与朋友的频率进行比较。 对于每个值，计算丢失了多少个副本。 
6. 如果丢失的副本总数最多为一份，则接受该分区。 如果为零，则仅由朋友即可形成目标。 如果是，特拉维斯就会选择那个缺失的球衣号码。 如果大于一，单件球衣就无法完成构造。 
7. 如果任何分区被接受，则打印`1`。 如果每个分区都失败，则打印`0`。 

### 为什么它有效

 考虑最喜欢的整数的任何有效构造。 该结构中的每个球衣号码都有一位或两位数字，因此该结构会产生目标十进制字符串的唯一分区。 我们的枚举检查该分区。 当朋友可以提供所有必需的球衣副本以及特拉维斯选择的最多一件球衣时，其频率比较就准确。 因此，每个有效的构造都被接受。 相反，每个接受的分区都描述了一系列合法的球衣号码，其串联正是目标，并且频率测试保证了在 Travis 选择一个缺失值（如果需要）后所需的副本实际上存在。 因此算法返回`1`确切地说，当存在有效的构造时。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = input().strip()
    n = int(input())
    friends = list(map(int, input().split()))

    freq = [0] * 100
    for x in friends:
        freq[x] += 1

    length = len(t)

    # There are length - 1 possible cut positions.
    # A mask describes which positions are cuts.
    for mask in range(1 << (length - 1)):
        need = [0] * 100
        pos = 0
        missing = 0
        valid = True

        while pos < length:
            if pos + 1 < length:
                # If there is a cut after this digit, use one digit.
                if mask & (1 << pos):
                    value = ord(t[pos]) - ord('0')
                    pos += 1
                else:
                    # Otherwise use two digits.
                    if t[pos] == '0':
                        valid = False
                        break
                    value = (ord(t[pos]) - ord('0')) * 10
                    value += ord(t[pos + 1]) - ord('0')
                    pos += 2
            else:
                value = ord(t[pos]) - ord('0')
                pos += 1

            if value == 0:
                valid = False
                break

            need[value] += 1

        if not valid:
            continue

        for value in range(1, 100):
            if need[value] > freq[value]:
                missing += need[value] - freq[value]
                if missing > 1:
                    break

        if missing <= 1:
            print(1)
            return

    print(0)

if __name__ == "__main__":
    solve()
```频率数组存储朋友的多重套装，而不仅仅是他们不同的球衣值。 这是必要的，因为有两份球衣`7`与一份球衣的资源不同`7`。 

掩码对于相邻目标数字之间的每个间隙都有一位。 当被咬时`pos`设置后，数字位于`pos`当前球衣结束，因此下一件开始于`pos + 1`。 当情况清楚时，我们一起消耗两个数字。 由于球衣号码最多有两位数，因此这是仅有的两种可能性。 

最后一位数字必须始终作为一位数字球衣使用。 循环通过以下方式处理这个问题`pos + 1 < length`条件，避免最后一位数字的越界访问。 

支票`t[pos] == '0'`在创建两位数之前，可以防止诸如以下的值`01`被视为球衣`1`。 分开的`value == 0`检查拒绝独立的零。 

这`missing`对策是资源短缺，而不是试图提前决定特拉维斯应该选择哪件球衣。 如果恰好缺少一个副本，则该值是 Travis 的最佳选择。 如果没有丢失任何副本，他的球衣就无关紧要，因为他不必使用它。 

Python 整数具有任意精度，因此不存在溢出问题。 更重要的是，目标被保存为字符串，因此没有理由对潜在的长连接值执行算术。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(2^L * L + 2^L * 99) = O(2^L * 99)`|`L <= 9`，因此最多检查 256 个分区 |
 | 空间|`O(99)`| 频率数组的固定大小为 100 |

 最大的目标只有 9 位数字，因此该算法最多检查 256 个分区。 即使扫描每个分区的所有 99 种可能的球衣值也只需要大约 25,000 次简单操作。 与 Codeforces 问题报告的 256 MB 限制相比，这完全在两秒限制之内，并且使用的内存可以忽略不计。

 对于一位数目标，例如```
