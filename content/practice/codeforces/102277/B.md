 ## 解决方案
 ## 问题理解

 任务是根据每个字母出现频率的奇偶性对小写字符串进行分类。 即使每个字母出现偶数次，也会调用字符串。 当每个小写字母出现奇数次时称为奇数。 如果两个条件都不成立，则答案为 2。输入包含一个长度最多为 70 的非空小写字符串，输出为单个整数，偶数字符串为 0，奇数字符串为 1，否则为 2。 

小长度范围极大地改变了实际情况。 即使是针对 26 个小写字母中的每一个扫描整个字符串一次的解决方案也最多执行 (26 × 70 = 1820) 个字符检查，这在一秒的限制下是微不足道的。 单遍仍然是更干净的解决方案，因为所需的信息只是每个字符频率的奇偶性。 

第一个边缘情况是单字符字符串。 例如，输入`a`应该产生`1`， 因为`a`出现一次，而其他所有小写字母出现零次。 零是偶数，一是奇数，因此仅当每个字母出现的次数恰好是奇数时，每个字母的频率才为奇数。 这意味着正确的结果为`a`实际上是`2`， 不是`1`。 如果不小心实现，只检查字符串中出现的字母，就会错误地将其分类为奇数。 

第二种边缘情况是每个小写字母只包含一次的字符串。 例如，`abcdefghijklmnopqrstuvwxyz`产生`1`。 26个字母每一个都出现一次，很奇数。 仅检查所有观察到的计数是否为奇数的实现可以正确处理这种情况，而忘记缺失字母的频率为零的实现也会错误地接受较短的字符串，例如`a`。 

第三种边缘情况是长度为偶数的全相等字符串。 例如，`aaaa`产生`0`， 因为`a`出现四次，其他字母出现零次。 将“偶数”解释为仅具有偶数字符串长度的粗心实现可能会通过此示例，但会失败`aabbc`，其长度也是奇数，而其字母频率奇偶性决定了实际的分类。 

## 方法

 直接的暴力方法是独立考虑 26 个小写字母中的每一个。 对于每个字母，扫描整个字符串并计算该字母出现的次数。 知道所有计数后，检查 26 个计数是否全部为偶数，或者是否全部 26 个计数均为奇数。 这是正确的，因为定义仅取决于每个字母的频率奇偶性。 最大字符串长度为 70，最坏的情况精确执行 (26 × 70 = 1820) 个字符比较，再加上少量的簿记，因此它很容易足够快。 在规定的约束下，不存在任何输入大小会使这种特定的强力方法变得有问题。 

更干净的方法是避免重新扫描字符串。 维护 26 个计数器，每个小写字母一个，并在每次读取字符时递增相应的计数器。 一次通过后，检查所有 26 个计数器的奇偶性。 如果每个计数器都是偶数，则答案为 0。否则，如果每个计数器都是奇数，则答案为 1。如果两个条件都不成立，则答案为 2。 

关键的观察是，一旦奇偶性已知，实际频率就无关紧要了。 我们只需要通过每个计数的奇偶性来区分零、偶、奇即可。 由于字母表固定为 26 个字符，因此检查所有计数器是一项持续的工作。 

暴力破解之所以有效，是因为字母表很小，但它会重复检查相同的字符。 在一次共享遍历期间可以对所有字母进行计数的观察结果消除了这种重复，并将字符串处理减少为单遍。

 ## 算法演练

 1. 创建数组`cnt`有 26 个条目，最初全部为零。 入口`i`存储字母表索引为的小写字母出现的次数`i`。 
2.遍历每个字符`ch`在字符串和增量中`cnt[ord(ch) - ord('a')]`。 这张地图`a`通过`z`无需字典即可索引 0 到 25。 
3. 检查每个值是否`cnt`是均匀的。 如果是这样，则打印`0`，因为每个小写字母出现偶数次。 
4. 如果字符串不为偶数，检查是否每个值`cnt`很奇怪。 如果是这样，则打印`1`，因为每个小写字母出现奇数次。 
5. 如果两个条件都不成立，则打印`2`。 至少一个字母的频率为偶数，至少一个字母的频率为奇数，因此该字符串既不是偶数也不是奇数。 

不变量是，处理完字符串的任意前缀后，`cnt[i]`正是该前缀中相应字母出现的次数。 处理整个字符串后，数组包含每个小写字母的准确频率。 最终的两次奇偶校验直接匹配两个特殊分类的定义，因此剩余的情况必须为 2。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    cnt = [0] * 26

    for ch in s:
        cnt[ord(ch) - ord('a')] += 1

    if all(x % 2 == 0 for x in cnt):
        print(0)
    elif all(x % 2 == 1 for x in cnt):
        print(1)
    else:
        print(2)

if __name__ == "__main__":
    solve()
```第一行读取唯一的字符串并删除尾随的换行符。 输入保证包含小写字母，因此不需要额外的验证。 

这`cnt`数组直接对应26个字母。 表达式`ord(ch) - ord('a')`皈依者`a`到 0，`b`到 1，依此类推`z`到 25。每个字符只处理一次。 

第一个`all`检查整个字母表的偶数条件，包括未出现的字母。 缺失的字母计数为零，零是偶数，因此这些字母必须包含在测试中。 

第二个`all`检查奇怪的情况。 这就是为什么像这样的字符串`a`不属于奇数：其他 25 个字母的计数为零，即偶数。 

Python 中不存在整数溢出问题，最大计数仅为 70。输入包含单个测试用例，因此不需要测试用例循环。

import io

def solve():
    s = input().strip()

    cnt = [0] * 26

    for ch in s:
        cnt[ord(ch) - ord('a')] += 1

    if all(x % 2 == 0 for x in cnt):

    elif all(x % 2 == 1 for x in cnt):
        print(1)

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        old_stdout = sys.stdout
        sys.stdout = io.StringIO()
        solve()
        result = sys.stdout.getvalue()
        sys.stdout = old_stdout
        return result
    finally:
        sys.stdin = old_stdin
        input = old_input

 ## 边缘情况

 对于单字符输入`a`，该算法创建计数`a = 1`其他所有字母都等于零。 偶数测试失败是因为`a`有奇数频率。 奇数测试也失败，因为其他 25 个字母的频率为零。 结果是`2`，这避免了仅检查出现的字符的常见错误。 

对于输入`abcdefghijklmnopqrstuvwxyz`，每个计数器都是一个。 每个字母的偶数测试都会失败，而所有 26 个计数器的奇数测试都会成功。 结果是`1`。 这会练习完整的字母表，并确认该算法不会意外忽略字母表末尾附近的字母。 

为了`aaaa`，计数器`a`变为 4，并且所有其他计数器保持为零。 26 次计数都是偶数，所以结果是`0`。 该案例还证实该算法检查频率而不是不同字符的数量。 

为了`aabbccddeeffgghhiijjkkllmm`，每个小写字母恰好出现两次。 每个计数器都是偶数，包括输入中明确表示的所有字母，因此结果是`0`。 这是一个有用的边界情况，因为它包含整个字母表，同时保持每个频率均匀。 

为了`aab`，频率是`a = 2`,`b = 1`，所有剩余字母均为零。 有些计数是偶数，有些计数是奇数，因此全局条件都不成立，算法会打印`2`。 这捕获了错误地根据总字符串长度的奇偶校验而不是每个单独字母频率的奇偶校验来决定答案的实现。
