 ## 解决方案
 ## 问题理解

 我们得到一个分成几个单词的短语，我们可以通过从每个单词中获取前缀并按顺序连接这些前缀来构建首字母缩略词。 每个选定的前缀长度必须在 1 到 3 个字符之间（含 1 到 3 个字符），因此每个单词至少为最终字符串贡献一个字母，最多三个字母。 

生成的首字母缩略词必须满足可读性约束：从左到右扫描，如果它不连续包含三个辅音，则认为它是可发音的。 元音固定为集合{A, E, I, O, U, Y}，所有其他大写字母都是辅音。 

任务是为每个单词选择一个前缀长度，以便连接的结果可以发音，并且总长度最小化。 如果不存在这样的选择，我们将输出一个失败标记。 

限制总体来说很大：所有单词的字符总数可以达到 10^6。 这立即排除了任何尝试枚举所有可能的前缀组合的解决方案，因为每个单词最多有 3 个选择，最多提供 3^N 种可能性，即使对于适度的 N 也是不可行的。 

一个微妙的边缘情况来自于第一个字母已经创建强制辅音连奏的单词。 例如，如果多个单词以辅音开头，即使仅选择 1 个字母的前缀也可能违反约束。 

另一个重要的特殊情况是单词非常短时。 如果一个单词的长度为1或2，它的前缀选择是有限的，有时我们被迫采用一个辅音，这使得全局序列不可能保持有效。 

最后，最难的失败模式是每个单词都存在局部有效的前缀选择，但全局范围内任何组合都不可避免地会产生三个辅音。 一种逐字优化的天真的贪婪方法在这里失败了，因为一个单词的决定会影响未来的辅音积累。 

## 方法

 暴力方法会为每个单词尝试从 1 到 3 的前缀长度的所有可能选择，构建生成的首字母缩略词，并检查它是否可发音。 每次检查都会在线性时间内扫描结果字符串。 这导致了 3^N 个候选者，每个候选者都需要 O(总长度) 验证，这远远超出了限制。 

关键结构是约束仅取决于当前后缀的长度最多为两个辅音。 我们不关心字符串的完整历史，只关心当前在处理的单词和下一个前缀之间的边界有多少个连续的辅音。 

这立即建议对单词进行动态编程，其中状态跟踪我们当前有多少个尾随辅音，上限为 0、1 或 2。任何创建第三个连续辅音的尝试都是无效的并被丢弃。 

对于每个单词，我们尝试选择前缀长度 1、2 或 3，计算它贡献了多少个辅音（取决于它的前几个字母），并相应地转换 DP 状态。 因为只有每个单词的前三个字母很重要，所以我们预先计算每个前缀长度如何影响辅音运行状态。 

DP 为每个单词索引和尾随辅音计数保留可实现的最小总长度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(3^N·L) | O(3^N·L) | O(L) | 太慢了|
 | 最佳DP | O(N·3·3) | O(N·3) | 已接受 |

 ## 算法演练

 我们从左到右处理单词，同时保持较小的状态空间。

1. 定义一个 DP 表，其中 dp[i][c] 表示处理前 i 个单词后的最小总长度，以恰好 c 个连续尾随辅音结尾，其中 c 在 {0, 1, 2} 中。 任何 c ≥ 3 的状态都是无效的并且永远不会被存储。 这捕获了未来决策所需的所有信息。 
2. 初始化 dp[0][0] = 0，因为在处理任何单词之前我们没有字母，因此尾随辅音为零。 
3. 对于每个单词 i，考虑所有可能的先前状态 dp[i][c]。 如果某个状态无法到达，则会跳过该状态。 从这个状态开始，我们尝试 {1, 2, 3} 中的所有前缀长度 len，但受实际单词长度的限制。 
4. 对于选定的前缀长度 len，我们检查该单词的前 len 个字符，并计算该前缀在附加后会贡献多少个尾随辅音。 这是通过扫描前缀并更新局部辅音条纹来完成的：每当看到辅音时，我们就会增加一个计数器； 当看到元音时，我们将其重置为零。 最终的结果就是我们对全球国家的贡献。 
5. 我们将之前的尾随辅音计数 c 与所选前缀的贡献结合起来。 我们通过继续跨越边界的条纹来模拟串联：如果前缀以辅音开头并且 c 不为零，则条纹继续； 否则，当元音出现时，它会适当重置。 
6. 如果在任何时候产生的尾随辅音计数超过 2，我们将丢弃此转换。 否则，我们以最小成本更新 dp[i+1][new_c]，即 dp[i][c] + len。 
7. 处理完所有单词后，答案是 dp[N][0]、dp[N][1]、dp[N][2] 中的最小值。 如果全部都不可达，我们输出不可能。 

正确性取决于唯一禁止的模式是三个连续辅音，因此 DP 状态只需要记住最多两个尾随辅音。 

## 为什么它有效

 该算法将首字母缩略词的完整历史压缩为恒定大小的状态，因为未来的任何决定仅取决于最后一个或两个字符是否是辅音。 以相同数量的尾随辅音结尾的两个部分结构对于所有未来的扩展是可互换的，因为在检查约束时任何未来的前缀最多与两个先前的辅音相互作用。 这给出了前缀上的有效等价关系，并保证了 DP 的最佳子结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

VOWELS = set("AEIOUY")

def is_vowel(ch):
    return ch in VOWELS

def run_word_prefix(word, start_state, length):
    c = start_state
    for i in range(length):
        if is_vowel(word[i]):
            c = 0
        else:
            c += 1
            if c >= 3:
                return -1
    return c

def solve():
    n = int(input())
    words = [input().strip() for _ in range(n)]

    INF = 10**18
    dp = [[INF] * 3 for _ in range(n + 1)]
    dp[0][0] = 0

    for i in range(n):
        word = words[i]
        m = len(word)

        for c in range(3):
            if dp[i][c] == INF:
                continue

            for L in range(1, min(3, m) + 1):
                nc = c
                ok = True
                for j in range(L):
                    if is_vowel(word[j]):
                        nc = 0
                    else:
                        nc += 1
                        if nc >= 3:
                            ok = False
                            break
                if not ok:
                    continue

                dp[i + 1][nc] = min(dp[i + 1][nc], dp[i][c] + L)

    ans = min(dp[n])
    if ans == INF:
        print("*")
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```DP表`dp[i][c]`存储处理后可实现的最佳首字母缩略词长度`i`词与`c`尾随辅音。 该转换枚举最多 3 的前缀长度，并仅在所选前缀上模拟元音辅音规则，同时向前传送先前的尾随辅音状态。 

关键的实现细节是我们显式地模拟跨越边界的辅音条纹，而不是尝试预先计算复杂的前缀结构。 由于前缀的长度最多为 3，因此该模拟每次转换的时间恒定。 

无穷大值用于标记无法到达的状态，最终答案取所有有效结束状态中的最小值。

 有效的最佳构造是选择产生“KMOP”的前缀，实现最小有效长度 4。任何保持长度为 3 的尝试都会失败，因为它会在某个边界强制使用禁止的辅音三元组。 

这表明每个单词的本地选择是不够的； 需要 DP 来平衡全局前缀长度。 

### 示例 2

 输入：```
2
KNUTH
M
PRATT
```处理“M”后，DP 变得更加受限，因为单个辅音单词可以扩展现有的辅音条纹。 处理“PRATT”时，任何保留短前缀的尝试都会导致无效的条纹，从而强制选择更长的前缀。 

DP 通过拒绝创建三个连续辅音的状态来正确避免无效转换，最终找到最小的可行配置。

 ## 边缘情况

 关键的边缘情况是单词本身以三个连续辅音开头。 例如，像“SCH”这样的单词如果采用前缀长度 3 就已经违反了约束，因此算法必须避免选择该前缀长度。 DP 自然会通过丢弃产生连续 3 次的转换来处理此问题。 

另一个边缘情况是一系列全是辅音的单字母单词。 对于像 K M P 这样的输入，每个可能的首字母缩略词只是辅音的串联，任何长度 ≥ 3 都立即无效。 DP 以所有状态无法到达而结束，产生所需的故障输出。 

最后，元音完全重置条纹的情况很重要。 在辅音较多的单词之间插入像“A”这样的单词可以完全重置状态并解锁较短的解决方案，而贪婪策略经常会错过这些解决方案。
