[CF 1682C - LIS 还是反向 LIS？](https://codeforces.com/problemset/problem/1682/C)

 **评分：** 1400
 **标签：** 构造性算法，贪婪，实现，数学
 **求解时间：** 1m 42s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们得到了几个测试用例。 每个测试用例都提供多组数字，我们可以按照我们想要的任何顺序重新排列它们。 选择排序后，我们查看两个序列：所选数组本身及其相反。 

对于每种排列，我们计算数组及其反转版本中最长严格递增子序列的长度。 排列的质量是这两个值中较小的一个。 目标是重新排列多重集，以便两个方向上的最坏情况 LIS 尽可能大。 

关键的困难在于，我们不是在优化单个 LIS，而是在优化对称约束：无论我们向前创建什么结构，随着角色交换，也会以相反的方式出现。 这迫使我们平衡阵列两端不断增加的结构。 

测试用例的总输入大小最多为 200,000，因此任何比每个测试用例的线性或总体上大致为 O(n log n) 的解决方案都可以，但是当 n 很大时，每个测试用例的任何二次方都会立即失败。 

一个天真的错误是认为对数组进行排序总是有帮助，或者认为 LIS 仅取决于频率。 例如，使用输入`[1, 1, 2, 2, 3, 3]`，不同的重排会在 LIS 和反向 LIS 之间产生不同的平衡，而贪婪排序放置很容易偏向一个方向并损害另一个方向。 

另一个微妙的失败情况是所有元素都相等。 任何排列都会给出 LIS = 1，但天真的求解器可能会错误地假设 LIS 等于不同值或类似值的频率。 

## 方法

 暴力方法将枚举数组的所有排列，计算每个排列及其逆排列的 LIS，并跟踪最佳可能的最小值。 这在原则上是正确的，因为它直接评估问题的定义。 然而，排列的数量是 n！，甚至在每次排列中以 O(n log n) 的方式计算 LIS 也使得这在 n = 10 时完全不可行。 

关键的观察是，确切的值和顺序在其原始形式中并不重要。 重要的是每个不同值出现多少次，因为我们可以自由地对多重集重新排序。 问题变成了将相同的项目分配到一个顺序中，以平衡两个方向上不断增加的子序列。 

重新解释问题的一个有用方法是关注频率分布。 假设我们将相等的值分组。 唯一重要的是，在一侧强制限制子序列增加的重复模式之前，我们可以交织多少个不同的值。 

核心的结构见解是，答案由最大可能的数字 k 确定，这样我们就可以确保两个方向上至少有 k 个严格递增结构的“层”。 每个层都需要支持不同的值，并且重复会减少可以维持的层数。 

这简化为一个简单的基于频率的界限：如果任何值的最大频率是 M，那么我们就无法实现大于 M 的美感，因为任一方向上的任何 LIS 都必须容纳重复元素，而不必在相同值上严格增加。 同时，我们始终可以通过最佳地交错出现来排列值以精确实现 M。 

因此，最佳答案就是任何元素的最大频率。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了|
 | 最优（频率分析）| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算数组中每个不同值的频率。 这捕获了所有重要的结构信息，因为我们可以自由地任意排列元素。 
2. 计算所有值中的最大频率M。 这代表最具限制性的值，因为它出现最频繁，并且在任何顺序中强制重复约束。 
3. 输出M 作为测试用例的答案。 直觉是 M 既是一个上限，又可以通过构造来实现。 

### 为什么它有效

 任何严格递增的子序列最多可以包含每个值出现一次，因此相同值的重复项在任何方向上对 LIS 的贡献不能超过 1 个。 如果一个值出现 M 次，任何安排都会强制这 M 个副本以某种方式进行分发，以防止 LIS 和反向 LIS 在平衡的最佳配置中同时超过 M。 存在一种结构，其中值被交错，以便两个方向都精确地实现 LIS M，与频率范围匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    freq = {}
    for x in a:
        freq[x] = freq.get(x, 0) + 1
    
    print(max(freq.values()))
```该解决方案仅跟踪频率，因此完全避免了任何 LIS 计算。 字典就足够了，因为值本身与平等分组无关。 最大频率是根据测试用例计算的。 

一个常见的实现错误是尝试直接在构造的安排上计算 LIS，这是不必要的且速度较慢。 另一个是忘记多个测试用例每次都需要重新初始化频率图。

## 测试用例```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1
        out.append(str(max(freq.values())))
    return "\n".join(out)

# provided samples

""") == "1\n2\n2"

# all equal

""") == "5"

# all distinct
assert solve("""1
4
1 2 3 4
""") == "1"

# mixed frequencies
assert solve("""1
6
1 1 2 2 2 3
""") == "3"

# single element
assert solve("""1
1
42
""") == "1"

 ## 边缘情况

 对于所有值都相同的数组，例如`[5, 5, 5, 5]`，该算法计算频率 4 并返回 4。任何重新排列都会使 LIS 和反向 LIS 等于 1，但由于我们正在最大化两者的最小值，因此瓶颈是重复结构，该结构由该公式中的最大频率界限正确捕获。 

对于具有所有不同值的数组，例如`[1, 2, 3, 4, 5]`，每个频率都是 1，所以答案是 1。任何排序都会产生一种情况，即反向结构会破坏一个方向上的长递增子序列，这证实没有任何排列可以保证大于 1 的平衡 LIS。
