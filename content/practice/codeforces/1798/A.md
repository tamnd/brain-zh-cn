 ## 解决方案
 ## 问题理解

 我们有两个长度相等的数组，我们可以将其视为并行的图块序列。 每个图块都有两个数字：一个在“a”侧，一个在“b”侧。 我们可以根据需要多次交换单个图块上的数字。 目标是使数组的最后一个元素`a`最大的`a`和数组的最后一个元素`b`最大的`b`同时地。 

约束告诉我们两个数组的长度最多为 100 个元素，值最多为 100。测试用例的数量最多为 200。这意味着解决方案具有双循环`n`是可行的，但是任何带有嵌套循环的操作都会太慢。 每个操作都是一个索引的本地操作，因此我们应该寻找一种贪婪或基于排序的方法，而不是全局模拟。 

非明显的边缘情况包括已排序的数组、两个数组中都出现一个最大值但位置不同的数组，以及长度为 1 的数组。 例如，与`a = [1]`和`b = [2]`，答案很简单“是”，因为每个数组只有一个元素。 另一个棘手的情况是当最大值处于冲突位置时，例如`a = [1, 3]`和`b = [4, 2]`。 我们需要智能地交换以满足这两个条件。 

## 方法

 一种强力方法是尝试每个指数的所有可能的掉期组合。 由于每个索引都有两个选择（交换或不交换），因此有`2^n`总的可能性。 和`n`达到100，这是一个天文数字，而且是不可行的。 

关键的见解是每次掉期仅影响当前指数。 我们可以在每个索引处本地决定哪个值应该进入`a`并进入`b`使数组在忽略最后一个元素时不减少。 为了满足最后一个位置的条件，我们想要所有`a[i] <= a[n]`和所有`b[i] <= b[n]`交换后。 这将问题简化为贪心检查：在每个位置，我们确保较大的数字进入`a`并且较小的到`b`。 如果任何索引在本地交换后违反了这一点，则不可能同时满足这两个条件。 

这一观察结果直接导致了线性时间解。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 贪婪交换检查 | 每个测试用例 O(n) | O(1) 额外 | 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 
2. 对于每个测试用例，请阅读`n`和两个数组`a`和`b`。 
3. 从 0 到 n-1 迭代每个索引。 在每个索引处，考虑该对`(a[i], b[i])`。 将两个数字中较大的一个分配给`a[i]`并且较小的到`b[i]`。 
4. 处理完所有索引后，检查数组是否`a`在最后一个位置有最大值并且`b`在最后一个位置有最大值。 
5. 如果两个条件都满足，则打印“Yes”。 否则，打印“否”。 

为什么它有效：贪心步骤确保`a[i]`永远不会大于`a[n]`对于任何 i 和`b[i]`永远不会大于`b[n]`。 如果可能的话，在每个索引处进行本地交换可以保证最后一个元素可以成为其数组中的最大值。 如果任何值无法放置在正确的数组中，则最后的检查会检测到这一点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    possible = True
    for i in range(n):
        if a[i] > b[i]:
            a[i], b[i] = a[i], b[i]  # keep a[i] >= b[i] invariant
        # ensure larger goes to a[i] for the greedy invariant
        if a[i] > b[i]:
            a[i], b[i] = a[i], b[i]
    
    if max(a) == a[-1] and max(b) == b[-1]:
        print("Yes")
    else:
        print("No")
```我们使用以下方法有效地读取输入`sys.stdin.readline`。 交换逻辑确保`a[i] >= b[i]`每一步之后。 检查最后位置的最大值可以确认贪婪分配是否足够。 我们不需要额外的数组，并且复杂度是线性的`n`每个测试用例。
