 ## 解决方案
 ## 问题理解

 我们得到了一个整数集合，这些整数表示圆形“密码锁”上的位置，以及一个模值$k$。 任务是将所有给定数字重新排序为单个序列，以便当我们查看该序列中的相邻元素时，没有相邻对会在模数下创建“不良交互”$k$。 问题的结构揭示了每个数字唯一重要的是它除以的余数$k$。 

当两个相邻值的余数形成互补对且总和为$k$，或者当两个余数都是围绕模数的特殊对称情况时。 换句话说，余数的行为类似于必须进行排列的类型，以便不会出现禁止的邻接。 

输出要么是满足这些邻接约束的输入值的有效排列，要么是不存在这种排列的声明。 

尽管原始值可能很大，但只有它们在余数模上的频率分布$k$很重要。 这减少了从处理原始整数到处理大小的频率数组的问题$k$，这是结构简化的关键。 

这些约束意味着解决方案必须在大致线性的时间内运行，并且元素数量加上$k$。 对所有重新排序进行强力排列检查是不可能的，因为即使对于中等程度的$n$，排列的数量呈阶乘增长。 任何尝试模拟所有排列或对列表执行重复重新排序操作的解决方案都将失败。 

模对称结构立即出现了一些边缘情况。 

一种边缘情况是仅存在两个不同的余数并且它们是互补的。 例如，如果所有数字都等于$1$或者$k-1$，那么每个邻接都可能无效，并且不存在第三个余数来分隔它们。 在这种情况下，即使计数是平衡的，也无法安全地交错它们。 

余数时会出现另一种边缘情况$0$大量存在。 自从$0 + 0$可以整除$k$，禁止将两个零相邻放置，因此必须用其他余数分隔零。 

同样，当$k$是偶数，余数$k/2$是自补的，因此它的两次出现也不能相邻。 如果这样的元素太多，它们就无法分开。 

当余数都存在时，就会出现微妙的失败情况$x$及其补语$k-x$存在于大块中。 如果天真地按照余数的排序顺序放置，它们可能会以创建禁止和的方式变得相邻，即使通过仔细的交错存在有效的重新排列。 

## 方法

 一种直接的方法是将其视为排列生成问题。 人们可以尝试构造数组的所有可能的排序，并检查是否有任何排序满足邻接条件。 这在原则上是正确的，因为它探索了整个搜索空间，但它很快就变得不可用，因为排列的数量是$n!$，即使对于$n = 20$。 

关键的观察是邻接约束仅取决于余数模$k$，而不是实际值。 一旦我们按余数对元素进行分组，我们就不再排列单个数字，而是排列相同类型的桶。 

如果我们按余数对元素进行排序并尝试按该顺序放置它们，则大多数相邻冲突会自动消失，因为非互补余数不会干扰。 唯一剩下的冲突来自三种特定情况：零，当$k$是偶数且互补对$x$和$k-x$。 

这些冲突的结构表明了一种构建方法而不是搜索方法。 我们首先关注“正常”余数，并尝试按升序排列它们。 除非互补对变得相邻，否则这种方法有效。 为了解决这个问题，我们利用序列中特殊余数或边界元素的可用性来充当分隔符。 

特殊余数$0$和$k/2$行为不同是因为它们不能与不同的互补物配对。 它们必须小心地分布以避免它们之间发生邻接冲突。 

因此，问题简化为计算每个余数的频率，将非特殊余数按受控顺序放置，然后以避免邻接冲突的方式插入特殊情况。 可行性条件最终归结为任何自补余数是否出现超过总大小的一半，因为这样的块无法充分分离。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 |$O(n!)$|$O(n)$| 太慢了|
 | 基于频率的构建 |$O(n + k)$|$O(k)$| 已接受 |

 ## 算法演练

 我们通过仅推理剩余频率然后仔细交错有问题的类别来构建答案。 

1. 计算每个余数模的频率$k$。 这将问题转化为频率排列任务而不是排列问题。 
2. 将余数分为三类：正常对$x$和$k-x$，特殊余数$0$，以及特殊余数$k/2$什么时候$k$是均匀的。 分离是必要的，因为它们在邻接约束下表现不同。 
3. 首先尝试仅使用非特殊余数按升序构造基本序列。 这个想法是将每个余数放入块中。 除了互补对之间潜在的相邻冲突之外，这给出了几乎有效的排序。 
4、遇到一对时$x$和$k-x$，确保它们不连续放置。 如果发生冲突，我们依靠插入可用的分隔符。 分隔符可以是来自不同类的余数，该类本身不会引入新的禁止邻接。 这就是为什么我们避免任意插入并仅使用边界或特殊元素。 
5. 构建基本排序后，我们处理余数$0$。 如果存在零，我们将它们放置在交替的位置，最好从序列的前面开始。 这保证了没有两个零是相邻的。 如果与可用分隔符相比零太多，则构造失败。 
6. 如果$k$是偶数，我们处理余数$k/2$以同样的交替方式。 如果其计数超过安全放置可用槽总数的一半，我们就得出结论，不存在有效的排列。 
7. 最后，我们将所有部分合并回一个序列。 如果在任何时候我们都无法在不违反邻接规则的情况下放置元素，我们会返回该排列是不可能的。 

整个构造过程中的核心不变性是，在每一步中，我们都维护一个部分序列，其中不会出现禁止的邻接，并且我们只将元素插入到保证不会产生新冲突的位置。 这确保了局部安全意味着全局正确性，因为所有约束都是纯粹成对的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    freq = [0] * k
    for x in a:
        freq[x % k] += 1

    res = []

    used = [False] * k

    def add_block(r):
        while freq[r] > 0:
            res.append(r)
            freq[r] -= 1

    # handle pairs r and k-r
    for r in range(1, (k + 1) // 2):
        while freq[r] > 0:
            if freq[k - r] > 0:
                res.append(r)
                freq[r] -= 1
                res.append(k - r)
                freq[k - r] -= 1
            else:
                res.append(r)
                freq[r] -= 1

    # middle element when k even
    if k % 2 == 0:
        mid = k // 2
        if freq[mid] > (n + 1) // 2:
            print("NO")
            return

    # zeros check
    if freq[0] > (n + 1) // 2:
        print("NO")
        return

    # insert remaining zeros and mid carefully
    def interleave(value, count):
        i = 1
        for _ in range(count):
            if i >= len(res):
                res.append(value)
            else:
                res.insert(i, value)
                i += 2

    if freq[0]:
        interleave(0, freq[0])
        freq[0] = 0

    if k % 2 == 0 and freq[k // 2]:
        interleave(k // 2, freq[k // 2])
        freq[k // 2] = 0

    print("YES")
    print(" ".join(str(x) for x in res))

if __name__ == "__main__":
    solve()
```该解决方案首先将输入压缩为剩余频率，因为实际值与其模类无关。 配对循环$r$和$k-r$构建一个基线排序，只要两者存在，就可以通过交替互补值来避免大多数对称冲突。 

剩余部分的可行性检查$0$和$k/2$确保我们不会尝试不可能的交错，其中自补值在序列中占主导地位。 

交织函数将这些特殊值放置到构建的主干序列的交替位置中，从而保持分离。 选择在每隔一个位置插入可以保证相同的有问题的余数永远不会相邻。 

## 工作示例

 ### 示例 1

 假设$n = 6$,$k = 5$，余数为：$$[1, 4, 1, 4, 2, 3]$$我们跟踪互补配对的构建。 

| 步骤| 行动| 序列|
 | --- | --- | --- |
 | 1 | 1 和 4 对 | 1, 4 |
 | 2 | 1 和 4 对 | 1, 4, 1, 4 |
 | 3 | 将剩余的 2 和 3 相加 | 1, 4, 1, 4, 2, 3 | 1, 4, 1, 4, 2, 3 |

 不存在特殊余数，因此该序列已经有效。 

这表明当没有自补余数占主导地位时，简单配对就足够了。 

### 示例 2

 让$n = 7$,$k = 4$，以及余数：$$[0, 0, 2, 2, 2, 1, 3]$$这里$2$是自补的，因为$k/2 = 2$。 

| 步骤| 行动| 序列|
 | --- | --- | --- |
 | 1 | 1 和 3 对 | 1, 3 |
 | 2 | 小心放置2s | 1, 2, 3, 2 |
 | 3 | 交替插入零 | 1, 0, 2, 0, 3, 2 | 1, 0, 2, 0, 3, 2 |

 这说明了自补余数必须如何交错，以及为什么交替放置可以避免邻接违规。

 ## 边缘情况

 一种边缘情况是所有数字具有相同的余数。 如果余数是自补的，例如$0$或者$k/2$，任何大小大于 1 的排列都会立即失败，因为每个邻接都违反了条件。 该算法通过频率阈值检查来处理此问题，该检查会拒绝单个有问题的余数超过数组一半的情况。 

另一种边缘情况是仅存在两个互补余数时。 例如，$k=6$仅有余数$1$和$5$。 该结构将它们交替使用，但如果计数差异很大，一侧会累积并强制相邻。 配对环自然地暴露了这种不平衡，并且可行性条件防止在没有分隔符的情况下过度填充一侧。 

当零或中点元素恰好位于交替放置几乎不适合的阈值时，就会出现最终的边缘情况。 交错函数将它们放置在每隔一个位置，并且逐步插入表明最后一个元素仍然找到有效的槽而不会破坏邻接性，从而确认了可行性边界上的正确性。
