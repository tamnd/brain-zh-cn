 ## 解决方案
 ## 问题理解

 我们有几个数组，对于每个数组，我们考虑每个可能的连续子数组。 对于每个子数组，我们将其“权重”定义为其内部包含相同值的位置对的数量。 换句话说，在选定的段内，我们查看所有索引对并计算有多少对具有相同的元素。 

任务是计算数组的所有子数组的总权重。 我们必须为整个数组有效地聚合该值，而不是独立评估每个子数组。 

这些约束足够严格，任何显式枚举子数组的解决方案都会立即变得太慢。 每个测试用例最多允许 100,000 个元素，并且最多可以有 100,000 个测试用例。 尽管所有测试的总长度是有界的，但每次测试都采用二次或接近二次的方法是不可能的。 每个测试用例的任何解决方案都必须接近线性。 

一种简单的方法会生成所有子数组并计算每个子数组中的相等对。 对于非常小的输入，例如，这已经失败了`n = 10^5`因为子数组的数量是 O(n^2)，并且计算每个子数组内的对会增加另一个因素。 

第二个常见的陷阱是尝试计算每个值的贡献，而没有正确考虑一对在不同子数组中出现的频率。 困难在于一对相等的元素不仅全局贡献一次，而且对包含两个端点的每个子数组贡献一次。 

## 方法

 蛮力策略首先迭代每个子数组`[l, r]`，并在里面计算有多少对`(i, j)`满足`l ≤ i < j ≤ r`和`a[i] = a[j]`。 这可以通过嵌套循环和每个子数组的频率表来完成。 即使我们在扩展的同时保持频率`r`，我们仍然有 O(n^2) 个子数组，并且更新计数为 O(1)，导致每个测试用例为 O(n^2)。 和`n = 10^5`，这远远超出了任何可行的极限。 

观察的关键是倒转观点。 我们不是首先对子数组求和，而是首先对相等位置对求和。 取两个索引`i < j`和`a[i] = a[j]`。 我们想知道这对子数组对权重有多少贡献。 

当且仅当子数组完全包含这两个元素时，它才会贡献这对元素`i`和`j`。 这意味着左端点`l`可以是来自任何地方`1`到`i`，以及右端点`r`可以是来自任何地方`j`到`n`。 因此，这对恰好出现在`i * (n - j + 1)`子数组。 

现在的问题变成了对所有相等对的贡献求和。 我们从左到右处理索引，维护每个值迄今为止出现的次数。 当我们处于位置时`j`, 之前的每一次出现`i`相同的价值贡献`i * (n - j + 1)`。 我们可以通过维护每个值的索引的运行总和来有效地积累这一点。 

这将问题简化为使用哈希图的单次传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1)-O(n) | O(1)-O(n) | 太慢了|
 | 最佳 | O(n) 摊销 | O(n) | 已接受 |

 ## 算法演练

 1. 我们从左到右处理数组，同时跟踪每个值的出现次数。 对于每个值，我们维护两条信息：到目前为止它出现了多少次，以及它之前的索引的总和。 
2. 当我们到达位置时`j`有价值`x`，我们想要计算这个位置对早期出现的对的贡献有多大`x`。 每个较早的索引`i`形成一对贡献`i * (n - j + 1)`。 
3.而不是迭代所有以前的`i`，我们使用存储的索引总和。 如果`S[x]`是之前所有位置的总和，其中`x`出现，则总贡献为`j`是`S[x] * (n - j + 1)`。 
4. 我们将此贡献添加到答案中。 
5. 然后我们更新存储的状态：增加计数并添加`j`总和`S[x]`。 
6. 对数组中的所有元素重复此操作并累加总答案。 

### 为什么它有效

 每个有效对`(i, j)`处理时具有相同值的仅计数一次`j`。 此时，算法已经累积了之前的所有位置`i`对于这个值。 每对这样的对都贡献了精确的`i * (n - j + 1)`子数组，并且乘法通过存储的和正确聚合。 由于每一对都唯一地归因于其右端点，因此不存在重复计算或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # store: value -> (count, sum of indices)
        cnt = {}
        idx_sum = {}
        
        ans = 0
        
        for j, x in enumerate(a, start=1):
            if x in idx_sum:
                ans += idx_sum[x] * (n - j + 1)
                cnt[x] += 1
                idx_sum[x] += j
            else:
                cnt[x] = 1
                idx_sum[x] = j
        
        print(ans)

if __name__ == "__main__":
    solve()
```为了使贡献公式更加清晰，该实现依赖于从 1 开始的索引`(n - j + 1)`。 字典`idx_sum`跟踪每个值的所有先前位置的总和。 当处理一个新的事件时，我们立即计算它与之前的事件完成了多少个子数组。 

一个微妙的点是我们永远不需要显式地使用`cnt`在最终计算中，但保留它有助于使状态在概念上完整。 正确性取决于更新`idx_sum[x]`将其用于当前索引后。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        idx_sum = {}
        ans = 0
        
        for j, x in enumerate(a, start=1):
            if x in idx_sum:
                ans += idx_sum[x] * (n - j + 1)
                idx_sum[x] += j
            else:
                idx_sum[x] = j
        
        out.append(str(ans))
    
    return "\n".join(out)

 ## 边缘情况

 对于所有相同值的数组，例如`[7, 7, 7, 7, 7]`，每个新元素都会与所有先前的元素相互作用。 在位置`j`，存储的总和增长为`1 + 2 + ... + (j-1)`，并且每个都乘以`(n - j + 1)`。 该算法正确地累积了这些不断增长的贡献，而不会丢失任何子阵列范围。 

对于单元素数组，根本不存在对。 循环运行一次，没有发现以前的事件，并且存储的映射仍然很简单。 输出保持为零，符合重量的定义。 

对于交替值，例如`[1, 2, 1, 2, 1, 2]`，每个值形成独立的出现链。 该结构确保贡献由密钥分隔，并且每对仅在到达其正确端点时才做出贡献，从而防止不同值之间的任何交叉干扰。
