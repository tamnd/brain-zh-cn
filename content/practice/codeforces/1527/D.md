 ## 解决方案
 ## 问题理解

 我们有一棵树，其顶点用整数标记`0`通过`n - 1`。 对于每对无序的不同顶点`(u, v)`，我们看看连接它们的独特简单路径。 该路径上出现的标签形成一组整数，我们计算该组的 MEX，即未出现的最小非负整数。 

任务是对每个值进行计数`k`从`0`到`n`，有多少个顶点对的路径 MEX 等于`k`。 

标签不是存储在顶点上的任意值。 顶点的标签就是它的索引。 这是问题的关键结构属性。 

所有测试用例的顶点总数最多为`2 · 10^5`，因此任何比每个测试用例的线性或近线性差得多的解决方案都是不可能的。 一棵树与`2 · 10^5`顶点包含关于`2 · 10^10`无序的顶点对，这会立即排除任何枚举路径的方法。 甚至一个`O(n²)`算法将大致执行`4 · 10^10`最坏情况下的操作。 

困难来自于间接计算路径，而不需要迭代它们。 

标签时出现微妙的边缘情况`0`不在路径上。 每条路都缺失`0`有墨西哥`0`，无论出现哪些其他标签。 

例如：```
0 - 1 - 2
```路径`(1,2)`包含标签`{1,2}`并拥有墨西哥`0`。 

当带有标签的顶点时会发生另一种重要情况`0,1,...,k-1`不可能全部都位于一条简单的路径上。 在这种情况下，没有路径可以同时包含所有这些，因此 MEX 的答案`k`必须为零。 

例如：```
    0
   / \
  1   2
```三个标签`{0,1,2}`不要躺在一条简单的道路上。 没有路径可以包含所有三个顶点，因此要求它们全部存在的每个答案都为零。 

错误的第三个来源是 MEX 的处理`n`。 对于墨西哥`n`，路径必须包含来自的每个标签`0`到`n-1`。 由于标签正是顶点，因此这样的路径必须访问树的每个顶点。 仅当整个树本身是一条简单路径时，这才有可能。 

## 方法

 强力解决方案将检查每对无序顶点，找到它们之间的路径，收集该路径上的标签，计算其 MEX，并增加相应的计数器。 

可以使用LCA预处理获得两个顶点之间的路径，但即使这样也有`Θ(n²)`对。 和`n = 2 · 10^5`，这变得完全不可行。 

关键的观察结果是 MEX 条件是由小标签定义的。 

假设路径有 MEX`k`。 

然后：```
0,1,...,k-1 must all appear on the path
k must not appear on the path
```别的都无所谓。 

让```
S_k = {0,1,...,k-1}
```一条路径有助于回答`k`当且仅当它包含的每个顶点`S_k`并且不包含顶点`k`。 

关键的结构事实是，只有当顶点集合包含在树的某个路径段中时，它们才能全部属于一条简单路径。 

定义`L`和`R`作为包含顶点的最小路径的端点`0..i`。 

在增加的同时`i`，我们维持这条路径。 

如果顶点`i`无法附加到当前端点结构，然后是顶点`0..i`不再包含在单个简单路径中。 一旦发生这种情况，每个更大的集合`0..j`也失败了，所有剩余的答案都变为零。 

整个解决方案围绕维护包含标签的路径`0..i`，然后计算有多少对端点生成包含所有顶点的路径`0..i-1`但不包括顶点`i`。 

计数本身是通过当前路径周围的组件大小来完成的。 

这将不可能的路径枚举问题转换为沿着动态增长的路径的一系列本地计数操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²·n) | O(n²·n) | O(n) | 太慢了|
 | 最佳 | 每个测试用例 O(n) | O(n) | 已接受 |

 ## 算法演练

 ### 预处理

 我们把树的根设在顶点`0`。 

使用 DFS 我们计算：

 - 每个顶点的父级
 - 子树大小
 - 欧拉进入和退出时间

 欧拉间隔允许恒定时间祖先检查。 

### 维护小标签的路径

 让当前路径包含来自的所有标签`0`通过`i`。 

最初：```
L = 0
R = 0
```对于每个新标签`i`我们确定它是否可以扩展当前路径。 

只有三种可能：

 1.`i`位于路径上`L`到`R`。 
2.`i`可以成为新的左端点。 
3.`i`可以成为新的右端点。 

如果这些都不成立，则顶点`0..i`不包含在任何简单路径中。 所有更大的答案都变成零，我们就停止了。 

### 计算包含所有必需标签的路径

 假设顶点`0..i-1`完全包含在路径内`(L,R)`。 

我们现在想要计算包含整个路径但不包含顶点的路径`i`。 

任何包含的路径`(L,R)`必须在附加的区域中选择一个端点`L`以及附加在区域之外的另一个端点`R`。 

有效选择的数量是这两个区域大小的乘积。 

我们使用子树信息和祖先关系来计算这些大小。 

### 连续 MEX 值之间的包含-排除

 让：```
f(i) = number of paths containing all vertices 0..i-1
```然后：```
answer[i] = f(i) - f(i+1)
```因为路径计数为`f(i+1)`正是那些也包含顶点的`i`。 

这会自动强制执行顶点的条件`i`必须缺席。 

### 墨西哥 0

 对于墨西哥`0`，我们需要不包含顶点的路径`0`。 

删除顶点`0`将树拆分为组件。 

完全位于一个组件内部的任何路径都会避免`0`。 

如果一个组件有尺寸`s`，它贡献：```
s(s-1)/2
```无序顶点对。 

对所有组件求和得出答案`0`。 

### 墨西哥 n

 价值：```
f(n)
```已经表示包含每个顶点的路径。 

This is exactly answer`n`。 

### 为什么它有效

 在每个阶段，维护的端点`(L,R)`描述包含迄今为止处理的标签的唯一最小路径。 当且仅当每个新插入的顶点可以从一个端点延伸当前路径时，一组顶点属于某个简单路径。 当该属性发生一次故障时，它就永远无法恢复。 

对于固定的`i`，每个包含标签的路径`0..i-1`必须包含整个最小路径`(L,R)`。 这样一条路径是通过从延伸过去的区域中选择一个端点来唯一确定的`L`另一个来自该地区延伸过去`R`。 将这些区域大小相乘会将每个有效路径恰好计数一次。 

自墨西哥以来`i`要求包含`0..i-1`并排除`i`，减去连续计数即可精确得出所需的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())

        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        parent = [-1] * n
        tin = [0] * n
        tout = [0] * n
        sz = [0] * n

        timer = 0

        stack = [(0, -1, 0)]
        while stack:
            v, p, state = stack.pop()

            if state == 0:
                parent[v] = p
                tin[v] = timer
                timer += 1

                stack.append((v, p, 1))
                for to in reversed(g[v]):
                    if to != p:
                        stack.append((to, v, 0))
            else:
                s = 1
                for to in g[v]:
                    if to != p:
                        s += sz[to]
                sz[v] = s
                tout[v] = timer

        def is_ancestor(a, b):
            return tin[a] <= tin[b] < tout[a]

        def on_path(x, a, b):
            return (
                is_ancestor(x, a) and is_ancestor(b, x)
            ) or (
                is_ancestor(x, b) and is_ancestor(a, x)
            )

        ans = [0] * (n + 1)

        total_pairs = n * (n - 1) // 2

        bad = 0
        for to in g[0]:
            if parent[to] == 0:
                s = sz[to]
            else:
                s = n - sz[0]
            bad += s * (s - 1) // 2

        ans[0] = bad

        f = [0] * (n + 1)

        L = 0
        R = 0

        def side_size(end, other):
            if is_ancestor(end, other):
                cur = other
                while parent[cur] != end:
                    cur = parent[cur]
                return n - sz[cur]
            return sz[end]

        f[1] = total_pairs

        alive = True

        for x in range(1, n):
            if not alive:
                break

            in_lr = on_path(x, L, R)
            in_lx = on_path(R, L, x)
            in_rx = on_path(L, R, x)

            if in_lr:
                pass
            elif in_lx:
                L = x
            elif in_rx:
                R = x
            else:
                alive = False
                break

            left_cnt = side_size(L, R)
            right_cnt = side_size(R, L)

            f[x + 1] = left_cnt * right_cnt

        for i in range(1, n):
            ans[i] = f[i] - f[i + 1]

        ans[n] = f[n]

        print(*ans)

solve()
```DFS 计算父指针、子树大小和欧拉时间戳。 这些是稍后需要的唯一结构数据。 

功能`is_ancestor`使用欧拉区间。 一个顶点`a`是的祖先`b`恰好当欧拉进入时间`a`包含进入时间`b`。 

维护的对`(L,R)`表示包含所有已处理标签的最小路径。 当新标签到达时，只有三种可能的几何关系。 如果都不起作用，则所需的顶点不再适合单个路径，并且所有后续计数都将变为零。 

帮手`side_size`计算有多少个顶点可以充当延伸到路径一侧之外的端点。 该公式取决于对端端点是否位于当前端点的子树内部。 

数组`f`存储包含小于阈值的所有标签的路径计数。 然后连续的差异产生精确的 MEX 频率。 

一个常见的实施错误是忘记了`answer[0]`遵循不同的计数规则。 墨西哥`0`表示路径必须避开顶点`0`，通过删除顶点最自然地计算`0`并对每个结果组件内的对进行求和。

 ## 边缘情况

 考虑一下明星：```
3
0 1
0 2
```删除顶点`0`留下两个孤立的顶点。 任一组件内都不存在无序对，因此回答`0`等于`0`。 

该算法通过求和直接计算：```
1·0/2 + 1·0/2 = 0
```现在考虑：```
    0
   / \
  1   2
```当标签`2`已处理，当前路径包含`{0,1}`是`1-0`。 顶点`2`无法扩展任一端点，同时保留包含所有标签的简单路径。 该算法检测到这一点并终止进一步的扩展。 每个较大的 MEX 答案都会自动变为零。 

最后考虑一条链：```
0 - 1 - 2 - 3
```所有标签都位于一条简单的路径上。 每次插入都会扩展一个端点，因此不变式永远不会中断。 最终值`f[n]`变成`1`，正确计算包含每个顶点的唯一路径。
