 ## 解决方案
 ## 问题理解

 Stepan 需要在严格增加的时间点发送一系列消息。 他的手机一开始的电量是有限的，开机时每单位时间的电量损耗是恒定的，如果他关闭然后重新打开手机，则会消耗固定的费用。 问题是他是否可以在电池电量为零的情况下安排所有消息。 

每个测试用例都提供消息数量、初始电池、单位时间消耗、切换电源的成本以及需要发送消息的确切时刻。 如果存在允许发送所有消息的开/关决策序列，我们必须输出“YES”，否则输出“NO”。 

约束条件表明所有测试用例的消息总和不超过 200,000 条，并且时刻最多可达$10^9$。 这排除了任何单独迭代每个时间单位的解决方案； 我们必须根据消息时间之间的差异进行推理。 边缘情况包括电池电量勉强维持到收到第一条消息的情况，或者打开和关闭手机比保持开机状态更便宜的情况。 

粗心的方法可能会模拟每个时间单位，或者忽略让手机打开还是关闭之间的选择，从而导致在最佳策略涉及切换的情况下输入错误答案。 

## 方法

 暴力方法会考虑从 0 到最后一条消息的每个时刻的手机状态，要么保持打开状态，要么关闭以节省电量。 对于每个时间单位，我们都会计算电池电量下降情况。 这在原则上是正确的，但$10^9$作为最大消息时间，按时间单位进行迭代是不可行的。 

关键的见解是，电池仅在离散时刻发生变化：在发送消息时以及在手机切换之前或之后。 在两条连续的消息之间，我们只需要决定是让手机保持开机状态更便宜还是将其关闭然后再次打开更便宜。 对于长度间隙$d$，让手机保持开启状态会消耗$a \cdot d$单位，同时关闭和打开消耗$b$单位。 因此，对于每个间隔，最小电池成本为$\min(a \cdot d, b)$。 我们从第一条消息开始累积这些成本，并检查剩余电池电量是否低于零。 

这一观察将问题简化为$O(n)$每个测试用例，因为我们只处理连续消息时刻之间的差异。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（模拟每个时间单位）| O(最大(m_i)) | O(1) | O(1) | 太慢了 |
 | 最优（贪心区间）| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量$t$。 
2. 对于每个测试用例，请阅读$n, f, a, b$以及消息时间列表$m$。 
3. 初始化剩余电量$f$。 
4. 迭代连续消息之间的间隙，包括当时的第一条消息$m_1$作为从 0 开始的间隙。计算间隙的长度$d = m_i - m_{i-1}$（和$m_0 = 0$）。 
5. 对于每个间隙，确定最小电池成本：$\min(a \cdot d, b)$。 从剩余电池电量中减去此值。 
6. 如果在任何时候电池电量降至 0 或以下，则中断并输出此测试用例的“NO”。 否则，在所有消息之后，输出“YES”。 

为什么它有效：算法总是在每个间隙中选择保持手机打开或关闭再打开之间更便宜的选项。 由于手机仅以两种方式消耗电池——打开时线性时间或切换时固定——这种贪婪的选择保证了每条消息的最小可能消耗，从而确保了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, f, a, b = map(int, input().split())
    m = list(map(int, input().split()))
    prev = 0
    battery = f
    possible = True
    for time in m:
        gap = time - prev
        cost = min(a * gap, b)
        battery -= cost
        if battery <= 0:
            possible = False
            break
        prev = time
    print("YES" if possible else "NO")
```该代码使用有效地读取输入`sys.stdin.readline`对于多个测试用例。 对于每条消息，它都会计算与前一时刻的间隔，计算更便宜的成本，并更新电池。 这`battery <= 0`check 确保立即检测到 Stepan 无法发送消息的任何情况。 使用`min(a * gap, b)`捕捉到了本质的贪婪决策。

 ## 边缘情况

 当电池正好等于第一个间隔的成本时，算法正确地输出“NO”。 对于极大的间隙，乘以`a * gap`在某些语言中可能会溢出，但 Python 可以处理大整数，并且`min(a * gap, b)`正确的选择可以防止错误的溢出结果。 贪婪的选择保证了每个间隔的最小消耗，因此跳过切换的微妙情况不会导致错误的答案。
