 ## 解决方案
 ## 问题理解

 我们有一个数组`a`长度`n`。 另一个数组`b`包含`m`值，其中`m`至少是`n`。 

我们可以准确选择`n`元素来自`b`，然后以任意顺序排列这些选定的元素以形成一个新数组`c`。 目标是最大化$$\sum_{i=1}^{n} |a_i - c_i|.$$任务是找到这个总和的最大可能值。 

第一个观察结果是，所选元素的最终顺序完全在我们的控制之下。 我们没有被迫维持秩序`b`。 这将问题转化为匹配问题：`n`我们应该借鉴的价值观`b`，以及我们应该如何将它们与`a`？ 

约束足够大，二次或三次算法是不可能的。 在所有测试用例中，总大小`b`至多是`2 \cdot 10^5`，所以一个`O(m log m)`每个测试用例的解决方案是完全可以接受的，而类似的事情`O(nm)`在最坏的情况下会太慢。 

一些边缘情况很容易处理不当。 

考虑```
n = 3
a = [1, 1, 1]
b = [1, 1, 1, 1]
```每一种可能的选择都会产生差异`0`。 任何假设总是存在一些积极贡献的贪婪策略都会在这里失败。 

考虑```
n = 2
a = [5, 100]
b = [1, 2, 99, 100]
```总是取全局最小或全局最大的剩余值并不能得到最佳答案。 不同的立场可能更喜欢相反的极端。 

考虑```
n = 3
a = [50, 51, 52]
b = [1, 2, 3, 100, 101]
```最佳解决方案使用排序左端的一些元素`b`还有一些从右端开始。 将我们自己限制在最小的范围内`n`元素或仅最大的`n`元素错过了最佳值。 

挑战在于找到小值和大值的正确组合。 

## 方法

 暴力解决方案会尝试每个子集`n`元素来自`b`，然后是这些元素的每种可能的排列。 对于每种排列，我们计算总绝对差并保留最大值。 

这显然是正确的，因为它检查每个有效的数组`c`。 问题在于它的大小。 即使对于适度的值`n`，子集的数量是$$\binom{m}{n},$$并且每个子集都有`n!`可能的安排。 搜索空间几乎立即变得天文数字。 

我们需要利用绝对差异的结构。 

种类`a`并排序`b`。 

假设我们已经决定了`n`的元素`b`将被使用。 经典的重排论证认为，为了最大化绝对差异之和，小值应该与大值配对，反之亦然。 由于两个数组都可以自由重新排序，因此只有相对顺序很重要。 

关键洞察力甚至更强。 

排序后`a`，任意选择的值`b`有助于最优解的必须来自已排序的两端之一`b`。 直观地讲，中间值从来没有吸引力，因为极值与每个元素相比都会产生更大的绝对差异。`a`。 

这表明了一个两指针过程。 

让排序后的数组`a`被修复。 任何时候我们仍然有一个范围`[l, r]`排序中未使用的值`b`。 

对于剩余的最小元素`a`，只有两个有意义的选择：

 - 与它配对`b[l]`。 
- 与它配对`b[r]`。 

任何内部价值都受这些极端之一的支配。 

如果我们排序`a`，从小到大处理，总是决定是消耗最左边还是最右边的剩余值`b`，我们获得了动态规划风格的贪婪结构。 

编辑解决方案使用更简单的观察。 

对于已排序的数组`a`，可以通过从已排序的两端取值来构造最佳匹配`b`。 让

-`k`元素来自左侧`b`,
 -`n-k`元素来自右侧`b`。 

修复后`k`，最好的配对是强制的。 

第一个`k`的最小元素`a`应与`k`所选左块中的最大值，而其余元素应与所选右块中的最小值进行匹配。 

我们可以评估每一种可能`k`排序后的线性时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 | O(m log m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 排序`a`按非递减顺序。 
2. 排序`b`按非递减顺序。 
3. 预计算$$L_i = |a_i - b_i|$$对于第一个元素的情况`a`与从左端获取的值匹配`b`。 

1. 预计算$$R_i = |a_i - b_{m-n+i}|$$对于以下元素的情况`a`与从右端获取的值匹配`b`。 

1. 构建前缀和`L`。 
2. 构建后缀和`R`。 
3.对于每一个`k`从`0`到`n`，假设恰好`k`值是从排序的左侧获取的`b`。 
4. 贡献者`k`对是从前缀和获得的`L`。 
5. 剩余部分的贡献`n-k`对是从后缀和获得的`R`。 
6. 取所有选择中的最大值`k`。 

这样做的原因是一旦`k`是固定的，所选择的元素就完全确定了。 我们采取第一个`k`已排序的值`b`和最后一个`n-k`已排序的值`b`。 排序数组的最佳配对直接来自匹配相反的极端情况。 

### 为什么它有效

 排序后，任何最优解都只使用两端的元素`b`。 如果在使用某些选定的内部元素时存在未使用的极端，则用极端替换内部元素只能增加或保留每个相关的绝对差异。 

固定一个值`k`。 所选集合由第一个组成`k`元素和最后一个`n-k`已排序的元素`b`。 

对于左边的块，最大的选择值应该与最小的值配对`a`，产生由前缀部分表示的贡献。 

对于右边的块，最小的选择值应该与最大的值配对`a`，产生由后缀部分表示的贡献。 

每个可行的最优解恰好对应于一个值`k`，公式会评估该选择的最佳值。 取所有的最大值`k`检查所有可能的最佳结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())

        a = sorted(map(int, input().split()))
        b = sorted(map(int, input().split()))

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + abs(a[i] - b[i])

        suff = [0] * (n + 1)
        for i in range(n - 1, -1, -1):
            suff[i] = suff[i + 1] + abs(a[i] - b[m - n + i])

        ans = 0

        for k in range(n + 1):
            ans = max(ans, pref[k] + suff[k])

        print(ans)

solve()
```对两个数组进行排序后，该解决方案构建两个累积数组。`pref[k]`存储第一次时获得的总贡献`k`的元素`a`与第一个匹配`k`的元素`b`。`suff[k]`存储仓位的贡献`k`通过`n-1`当这些元素与最右边的元素匹配时`n-k`的值`b`。 

对于固定分割点`k`，左边部分来自`pref[k]`正确的部分来自`suff[k]`。 添加它们给出了从排序左侧取出多少元素的特定选择的答案`b`。 

整个循环`k`检查每个可能的分割并保留最大的结果。 

所有算术都使用 Python 整数，它可以安全地处理远大于最大可能答案的值。

 ## 边缘情况

 考虑```
1
3 4
1 1 1
1 1 1 1
```排序后，每个绝对差都为零。 前缀和后缀数组都保持为零。 每个分割点产生的总数为零，因此答案正确地报告为`0`。 

考虑```
1
2 4
5 100
1 2 99 100
```该算法对两个数组进行排序，并评估左右极值之间的每个分割`b`。 最佳分割使用两个极值`1`和`2`，生产```
|5 - 1| + |100 - 2| = 4 + 98 = 102
```最佳配对后。 总是先获取最大剩余值的贪心方法会错过这种可能性。 

考虑```
1
3 5
50 51 52
1 2 3 100 101
```最佳答案需要从排序的两端取值`b`。 拆分枚举自然会检查此配置，因为会评估左侧选择的每个可能数量。 无需特殊处理。
