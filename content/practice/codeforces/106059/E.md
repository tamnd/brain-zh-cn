 ## 解决方案
 ## 问题理解

 我们在数轴上得到了敌人的位置和观察者的位置。 对于每个观察者，我们关心距他们特定距离范围内的敌人。 

每个观察者所在位置`b`定义两个半径。 敌人最远距离`L`被认为距离太近而无法交战，而敌人则最多位于远处`R`是可见的。 该任务仅涉及与观察者的距离严格大于的敌人`L`并且至多`R`。 对于每个观察者，我们必须报告两个值：有多少敌人落入这个距离范围，以及他们到观察者的距离之和。 

关键的难点是两者`n`和`q`可以大到 200,000，因此任何为每个观察者检查每个敌人的解决方案都会太慢。 在最坏的情况下，双循环将执行大约 4e10 次距离检查，这远远超出了 Python 中 2 秒执行时间的限制。 

条件的结构也很重要。 每个查询仅取决于绝对距离，该距离自然地分成每个观察者周围的两个独立区域：左侧的敌人和右侧的敌人。 一个幼稚的错误是尝试将区间视为索引空间中的单个连续范围，这会失败，因为转换`|a - b|`是对称的，并且在不分裂的情况下不保序。 

出现微妙的边缘情况时`L = 0`。 在这种情况下，即使处于观察者位置的敌人在范围内，也会被排除`R`。 另一种情况是当所有敌人都在外面时`R`，答案应该是`0 0`，并且任何基于前缀和的解决方案都必须避免访问无效范围。 

## 方法

 直接方法通过扫描所有敌人并计算距离来独立评估每个观察者。 这是正确的，因为它遵循字面定义：对于每个敌人，计算`|a[i] - b[j]|`并检查它是否位于`(L, R]`，当它发生时累积计数和总和。 问题是这执行`n * q`距离计算。 两者都达到 200,000，这会导致 400 亿次操作，无法及时完成。 

该病症的结构提出了不同的观点。 我们可以将约束转换回数轴，而不是考虑距离。 不平等`L < |a - b| ≤ R`相当于两个不相交的线段：`[b - R, b - L)`在左侧和`(b + L, b + R]`在右侧。 这完全消除了绝对值，并将问题减少到静态排序数组上的范围计数。 

一旦敌人的位置被排序，我们就可以使用二分查找来回答任意区间内有多少个敌人的位置。 为了有效地计算距离和，我们在排序位置上维护一个前缀和数组。 这允许对任何段上的总和进行恒定时间计算，将每个查询转换为对数数量的边界搜索和恒定算术。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(1) | O(1) | 太慢了 |
 | 排序+二分查找+前缀和| O((n + q) log n) | O((n + q) log n) | O(n) | 已接受 |

 ## 算法演练

 我们首先对敌人位置数组进行排序，以便我们可以推断出线上的连续线段。 排序是将几何距离约束转化为区间查询的关键转换。 

接下来，我们在排序后的位置上构建一个前缀和数组。 这允许我们在定位其边界后在恒定时间内计算任何子数组的总和。 

对于每个观察者位置`b`，我们翻译条件`L < |a - b| ≤ R`分为排序轴上的两个区间。 左边的区间是所有敌人`[b - R, b - L)`，正确的区间是所有敌人`(b + L, b + R]`。 我们独立查询两者。 

对于每个区间，我们使用二分搜索来查找元素至少位于左边界的第一个索引和超出右边界的第一个索引。 这为我们提供了排序数组中的连续段。 

我们使用前缀和数组计算每个段中值的计数和总和。 然而，需要的输出是距离之和，而不是坐标之和，所以我们进行相应的转换。 对于右侧区间，每个贡献是`a[i] - b`，所以总计为`sum(a[i]) - count * b`。 对于左侧区间，每个贡献是`b - a[i]`，所以总计为`count * b - sum(a[i])`。 

最后，我们将双方的贡献相加，并输出组合的计数和距离总和。 

### 为什么它有效

 正确性依赖于绝对距离将线划分为相对于每个查询点的两个单调区域的事实。 排序后，表格的任意条件`a[i] ≤ x`或者`a[i] ≥ x`对应于一个连续的块。 该转换将几何过滤器转换为一对不相交的数组切片，并且前缀和确保这些切片上的计数和聚合都是精确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def lower_bound(arr, x):
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] < x:
            lo = mid + 1
        else:
            hi = mid
    return lo

def upper_bound(arr, x):
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] <= x:
            lo = mid + 1
        else:
            hi = mid
    return lo

n, q, L, R = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

a.sort()

pref = [0] * (n + 1)
for i in range(n):
    pref[i + 1] = pref[i] + a[i]

out = []

for x in b:
    cnt = 0
    dist_sum = 0

    left_l = x - R
    left_r = x - L
    l = lower_bound(a, left_l)
    r = lower_bound(a, left_r)
    c = r - l
    if c > 0:
        s = pref[r] - pref[l]
        cnt += c
        dist_sum += c * x - s

    right_l = x + L
    right_r = x + R
    l = upper_bound(a, right_l)
    r = upper_bound(a, right_r)
    c = r - l
    if c > 0:
        s = pref[r] - pref[l]
        cnt += c
        dist_sum += s - c * x

    out.append(f"{cnt} {dist_sum}")

print("\n".join(out))
```该实现依赖于显式二分搜索而不是`bisect`使边界行为透明。 重要的细节是在左右间隔上使用不同的包含性规则。 左边我们使用半开区间`[b - R, b - L)`，所以两个边界都使用`lower_bound`。 在右侧我们使用`(b + L, b + R]`，所以我们应用`upper_bound`两端。 

距离转换步骤是大多数实施错误发生的地方。 前缀和为我们提供了坐标之和，但问题要求绝对差之和。 该代码仔细地将它们转换为线性表达式`b`。 

## 工作示例

 考虑第一个样本输入。 

我们在阵地上有敌人`[4, 5, 6]`，以及两名观察者`1`和`10`， 和`L = 4`和`R = 5`。 

对于观察者`1`，有效距离是位置在`[ -4, -3 ]`在左边和`[5, 6]`翻译后在右边。 只有右侧有贡献。 间隔`(1 + 4, 1 + 5] = (5, 6]`仅包含`6`。 

| 观察者| 左间隔| 右间隔 | 计数 | 距离总和 |
 | ---| ---| ---| ---| ---|
 | 1 | 空 | [6] | 1 | 5 |

 这证实了该机制正确地分割了空间。 

对于观察者`10`，我们计算间隔`[1, 6)`和`(14, 15]`。 只有左侧有贡献，包含`4, 5, 6`。 

| 观察者| 左间隔| 右间隔 | 计数 | 距离总和 |
 | ---| ---| ---| ---| ---|
 | 10 | 10 [4,5,6]| 空 | 3 | 9 |

 这表明所有距离均使用正确累积`10 - a[i]`。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q, L, R = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    a.sort()

    pref = [0]
    for x in a:
        pref.append(pref[-1] + x)

    def lb(x):
        lo, hi = 0, n
        while lo < hi:
            mid = (lo + hi) // 2
            if a[mid] < x:
                lo = mid + 1
            else:
                hi = mid
        return lo

    def ub(x):
        lo, hi = 0, n
        while lo < hi:
            mid = (lo + hi) // 2
            if a[mid] <= x:
                lo = mid + 1
            else:
                hi = mid
        return lo

    res = []
    for x in b:
        cnt = 0
        s = 0

        l1, r1 = lb(x - R), lb(x - L)
        c = r1 - l1
        cnt += c
        s += c * x - (pref[r1] - pref[l1])

        l2, r2 = ub(x + L), ub(x + R)
        c = r2 - l2
        cnt += c
        s += (pref[r2] - pref[l2]) - c * x

        res.append(f"{cnt} {s}")

    return "\n".join(res)

 ## 边缘情况

 当所有敌人都处于精确的距离时`L`，必须将它们排除在外。 例如，敌人位于`[0, 5]`,`L = 5`，并观察者`0`，两个点都在距离`5`，所以两者都没有贡献。 该算法处理这个问题是因为左间隔使用`[b - R, b - L)`和正确的间隔使用`(b + L, b + R]`，明确排除边界`L`。 

什么时候`L = 0`，与观察者处于同一位置的敌人被排除。 对于单个敌人`0`和观察者`0`，左边的区间变成`[0, 0)`右边的区间就变成了`(0, R]`，所以点在`0`不计算在内，符合严格的不平等要求。 

当没有敌人落入其中时`[b - R, b + R]`，两个二分查找都会产生空段，并且 count 和 sum 都保持为零。 前缀和结构自然支持空间隔，因为相同的边界产生零差异。
