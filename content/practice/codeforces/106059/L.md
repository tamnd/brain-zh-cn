 ## 解决方案
 ## 问题理解

 问题本质上是要求我们沿着河岸处理一排灯笼，其中每个灯笼要么打开，要么关闭。 输入为我们提供了一个长度为 n 的序列，每个位置包含 0（表示灯笼未点亮）或 1（表示灯笼发光）。 任务是确定当前有多少个灯笼被点亮，相当于计算序列中有多少个值等于1。 

尽管该声明在节日背景下阐述了这一点，但除了原始价值之外，位置、邻接或结构都不重要。 该序列是独立的，每个元素都对答案做出贡献，而不与其他元素相互作用。 

约束 n 最大为 2 × 10^5 告诉我们我们需要在线性时间内扫描数组。 任何重复处理相同元素或在数组上使用嵌套循环的方法都会太慢。 在最坏的情况下，二次解意味着大约 4 × 10^10 次运算，这远远超出了时间限制。 这立即表明单次积累是正确的方向。 

这里的边缘情况主要与输入格式和边界大小有关。 如果 n = 1，我们只需返回该单个值。 如果所有值均为 0，则答案为 0。如果所有值均为 1，则答案为 n。 实现中可能出现的一个微妙问题是假设第二行始终格式化干净或包含恰好 n 个由空格分隔的整数，但忘记输入可能跨越需要快速解析的大行。 

## 方法

 解决该问题的一个直接方法是直接迭代灯笼状态列表并计算有多少个灯笼状态等于 1。这是可行的，因为每个灯笼对最终总数都有独立的贡献。 我们不需要排序、前缀结构或任何形式的预处理，因为位置之间不存在范围查询或依赖关系。 

蛮力解释可能仍然被表述为单独检查每个灯笼并在灯点亮时增加计数器。 这在结构上已经是最优的。 任何重复重新计算计数的尝试（例如重新计算每个查询位置的前缀之和）都是不必要的，因为该问题仅要求单个全局计数。 

关键的观察结果是输入的结构已经很小了。 不需要转换，只需聚合。 这将问题简化为计算二进制数组的总和，因为每个 1 只对答案贡献一个单位，而每个 0 则不贡献任何内容。

 | 最优（单次总和）| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们扫描一次序列，同时保持点亮灯笼的总数。 

1. 读出n，灯笼的数量。 这决定了我们将处理多少个值，并确保我们在消耗序列后准确停止。 
2. 将计数器初始化为零。 该计数器代表到目前为止已看到点亮的灯笼数量。 
3. 迭代输入序列中的每个 n 值。 每个值代表单个灯笼的状态。 
4. 对于每个值，检查它是否等于 1。如果等于，则将计数器加 1。 如果为 0，则不执行任何操作。 此步骤之所以有效，是因为每个灯笼都独立贡献，并且只有点亮的灯笼才对最终计数重要。 
5. 处理完所有值后，输出计数器。 此时，它包含输入序列中点亮的灯笼的总数。 

### 为什么它有效

该算法保持不变式，即在处理前 k 个元素后，计数器等于这 k 个元素中 1 的数量。 每个步骤都保留此不变式，因为更改前缀中点亮的灯笼的真实计数的唯一方法是包含当前元素（如果当前元素为 1）。由于每个元素仅处理一次，并且当且仅当它为 1 时才贡献一次，因此最终计数器等于完整序列中点亮的灯笼的总数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    arr = list(map(int, input().split()))
    
    cnt = 0
    for x in arr:
        cnt += x
    
    print(cnt)

if __name__ == "__main__":
    solve()
```该解决方案读取大小 n，然后将整个第二行解析为整数列表。 由于数值只有0或1，直接求和相当于数点亮的灯笼，既紧凑又高效。 

一个常见的陷阱是忘记剥离或正确分割输入线，尤其是当 n 很大时。 使用`sys.stdin.readline`确保快速阅读。 另一个微妙之处是，这里对整数求和是安全的，因为值很小，并且在 Python 中不存在溢出风险。

 ## 边缘情况

 对于值为 0 的 n = 1，算法将计数器初始化为 0，读取单个元素，发现它不是 1，然后输出 0。这与预期行为直接匹配，因为没有点亮的灯笼。 

对于 n = 1 且值为 1 的情况，计数器从 0 开始，递增一次，并输出 1。这确认了最小非平凡输入大小的正确性。 

对于全零的情况，例如 n = 5 和 [0, 0, 0, 0, 0]，每次迭代都会使计数器保持不变，因此最终结果仍为 0，与没有点亮灯笼的情况相匹配。 

对于所有 1，例如 n = 5 和 [1, 1, 1, 1, 1]，每次迭代都会递增计数器，因此它会精确累加 n。 这表明算法线性扩展，无需对密集输入进行任何特殊处理。
