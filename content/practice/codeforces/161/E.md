 ## 解决方案
 ## 问题理解

 我们有几个素数。 每个素数代表数字方阵的第一行。 如果素数有长度`n`，那么矩阵是`n × n`。 

矩阵必须满足两个条件。 

首先，解释为十进制数的每一行本身必须是素数。 除第一行之外的行允许以零开头。 

其次，矩阵是对称的。 位置上的数字`(i, j)`必须等于数字`(j, i)`。 

任务是计算每个给定的第一行存在多少个这样的矩阵。 

考虑矩阵的一个有用方法是：一旦第一行被固定，对称性也立即固定第一列。 那么剩下的每个选择都必须同时满足行素性和列一致性。 

最大素数长度仅为`5`，因为输入的数字最多为`99999`。 这完全改变了问题的性质。 尽管全数字矩阵的搜索空间很大，但实际维数却很小。 这强烈表明仔细修剪的强力或动态编程方法是可行的。 

测试用例数量最多为`30`，因此预处理很有吸引力。 有少于`100000`总共五位数字的字符串，并且只有大约`10^4`下面的素数`100000`。 我们可以枚举一次素数并在所有测试用例中重复使用它们。 

对所有可能的矩阵进行天真的搜索是没有希望的。 对于一个`5 × 5`矩阵，有`10^25`数字分配。 即使我们只考虑素数行，每行仍然有数千个候选，这会导致数万亿种组合。 

棘手的部分是行约束和对称性在两个方向上相互作用。 粗心的 DFS 很容易计算出无效矩阵。 

考虑输入：```
1
11
```答案是：```
4
```有效矩阵是：```
11
11
```

```
11
13
```

```
11
17
```

```
11
19
```第二行必须以`1`因为对称性。 任何以以下开头的两位素数`1`作品。 

另一个容易犯的错误是忘记第一行之外允许有前导零。 

对于输入：```
1
401
```行`"023"`是完全合法的，如果`23`是素数。 将行视为固定宽度的十进制字符串而不是整数会错误地拒绝这种情况。 

第三个微妙点是，每个行选择都会通过对称性约束未来的行。 假设第一行是`"239"`。 

选择第二行后`"307"`，对称力：```
2 3 9
3 ? ?
9 ? ?
```第三行必须以`"97"`因为列约束已经确定了这些数字。 如果我们只逐行检查素数而不强制执行这些前缀，我们就会计算无效矩阵。 

## 方法

 蛮力的想法很简单。 假设矩阵大小为`n`。 我们修复输入中的第一行，然后尝试第二行的每个可能的素数，第三行的每个可能的素数，依此类推。 构造完整矩阵后，我们检查它是否对称。 

这在逻辑上是有效的，因为每个候选矩阵都被直接检查。 问题在于分支因素。 大致有`10^4`下面的素数`100000`。 即使按数字长度进行限制，每行仍然有数千种可能性。 为了`n = 5`，搜索大致变为：```
3000^4 ≈ 8 × 10^13
```这是完全不可能的。 

关键的观察是对称性会产生前缀约束。 

当我们选择某些行时，我们会自动确定未来行的部分内容。 如果行`0..k-1`已经固定了，那么第一个`k`行的数字`k`受到对称性的强制。 

例如，选择后：```
239
307
```第三行必须以`"97"`因为：```
a[2][0] = a[0][2] = 9
a[2][1] = a[1][2] = 7
```这彻底改变了问题。 每行必须属于具有特定前缀的素数集合，而不是自由选择行。 

自从`n ≤ 5`，我们可以预处理按长度和前缀分组的所有素数。 然后搜索就变成了一个带有积极修剪的小型 DFS。 

在 DFS 深度`k`，我们已经确切地知道哪个前缀行`k`必须有。 我们只迭代与该前缀匹配的素数。 每个有效的选择都会一致地扩展矩阵。 

这将对所有素数元组的指数搜索变成了更小的状态空间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数，大致为 O(P^(n-1)) | O(n²) | 太慢了 |
 | 最佳 | O(有效 DFS 状态数) | O(P)| 已接受 |

 这里`P`是最多 5 位素数的个数。 

## 算法演练

 1. 生成下面所有素数`100000`使用筛子。 

我们需要每个长度的素数`1`通过`5`，因为第一个之后的行可能包含前导零。 例如，`"023"`对应于素数`23`。 
2. 将每个素数转换为长度为零的填充字符串`1`通过`5`。 

例如，素数`23`变成：```
"23"   for length 2
"023"  for length 3
"00023" for length 5
```这让我们可以自然地处理前导零。 
3. 对质数进行分组`(length, prefix)`。 

对于每个填充的素数字符串，将其存储在以其前缀为键的字典中。 

长度示例`3`:```
prefix "9"  -> ["907", "911", ...]
prefix "97" -> ["977", ...]
```稍后，当一行被迫开始时`"97"`，我们可以立即检索所有兼容素数。 
4. 对于每个测试用例，将第一行存储为 row`0`。 

由于矩阵是对称的，因此第一列也会自动固定。 
5. 逐行运行DFS。 

假设我们选择行`k`。 

因为行`0..k-1`已经固定了，对称性决定了第一个`k`行的数字`k`。 

具体来说：```
row[k][j] = row[j][k]
```对于每一个`j < k`。 
6. 为行构建所需的前缀`k`。 

如果当前行是：```
239
307
```然后行`2`必须从以下内容开始：```
rows[0][2] + rows[1][2] = "97"
```7. 枚举与该前缀匹配的每个素数行。 

检索所有长度的素数`n`带有预处理字典中所需的前缀。 
8. 追加一个候选行并继续递归。 

每个选定的行都会自动保留与所有先前行的对称性，因为其强制前缀已经匹配。 
9.当所有`n`选择行，计算一个有效矩阵。 

### 为什么它有效

 在 DFS 深度`k`, 行`0..k-1`它们之间已经满足对称性。 第一个`k`行的数字`k`由条件唯一确定：```
a[k][j] = a[j][k]
```选择具有完全相同的前缀的任何素数可以保留与所有现有行的对称性。 未来的行稍后将强制涉及行的剩余对称位置`k`。 

不计算无效矩阵，因为每个对称约束在确定时都会强制执行。 不会遗漏任何有效矩阵，因为会探索与所需前缀匹配的每个合法行。 

## Python 解决方案```python
import sys
from collections import defaultdict

input = sys.stdin.readline

LIMIT = 100000

# sieve
is_prime = [True] * LIMIT
is_prime[0] = is_prime[1] = False

for i in range(2, int(LIMIT ** 0.5) + 1):
    if is_prime[i]:
        step = i
        start = i * i
        for j in range(start, LIMIT, step):
            is_prime[j] = False

# prefix[length][prefix] = list of prime strings
prefix = [defaultdict(list) for _ in range(6)]

for x in range(2, LIMIT):
    if not is_prime[x]:
        continue

    s = str(x)

    for length in range(len(s), 6):
        padded = s.zfill(length)

        for k in range(length + 1):
            pref = padded[:k]
            prefix[length][pref].append(padded)

t = int(input())

for _ in range(t):
    first = input().strip()
    n = len(first)

    rows = [first]
    ans = 0

    def dfs(k):
        nonlocal ans

        if k == n:
            ans += 1
            return

        need = []

        for j in range(k):
            need.append(rows[j][k])

        need = ''.join(need)

        for candidate in prefix[n][need]:
            rows.append(candidate)
            dfs(k + 1)
            rows.pop()

    dfs(1)

    print(ans)
```筛子生成下面的每个素数`100000`一次。 由于最大行长度仅为`5`，这个预处理很小。 

中央预处理结构是`prefix[length][pref]`。 它存储按前缀分组的每个固定长度的质数字符串。 这就是 DFS 快速的原因。 我们不是在递归过程中测试每个素数，而是直接跳转到兼容的候选素数。 

该行：```
padded = s.zfill(length)
```是必不可少的。 如果没有零填充，诸如`"023"`永远不会出现，即使它们代表有效的素数`23`。 

DFS 状态仅存储已选择的行。 选择行时`k`，所需的前缀由列构造`k`较早的行：```
rows[j][k]
```这恰好强制了对称性。 

递归深度最多为`5`，所以Python递归在这里是完全安全的。 

一个微妙的实现细节是我们从不在最后显式检查对称性。 施工过程逐步保证这一点。 每行都被迫在适当的位置匹配所有较早的行。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(可达 DFS 状态数) | 每个递归分支都对应一个有效的前缀兼容构造 |
 | 空间| O(P)| 所有填充素数字符串和前缀组的存储 |

 预处理处理的数量少于`100000`整数，这是微不足道的。 DFS深度最多为`5`，前缀修剪会立即删除几乎所有分支。 这很容易适合`3`第二个限制。 

## 测试用例```python
# helper: run solution on input string, return output string
import sys, io
from collections import defaultdict

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    LIMIT = 100000

    is_prime = [True] * LIMIT
    is_prime[0] = is_prime[1] = False

    for i in range(2, int(LIMIT ** 0.5) + 1):
        if is_prime[i]:
            for j in range(i * i, LIMIT, i):
                is_prime[j] = False

    prefix = [defaultdict(list) for _ in range(6)]

    for x in range(2, LIMIT):
        if not is_prime[x]:
            continue

        s = str(x)

        for length in range(len(s), 6):
            padded = s.zfill(length)

            for k in range(length + 1):
                prefix[length][padded[:k]].append(padded)

    t = int(input())
    out = []

    for _ in range(t):
        first = input().strip()
        n = len(first)

        rows = [first]
        ans = 0

        def dfs(k):
            nonlocal ans

            if k == n:
                ans += 1
                return

            need = ''.join(rows[j][k] for j in range(k))

            for cand in prefix[n][need]:
                rows.append(cand)
                dfs(k + 1)
                rows.pop()

        dfs(1)
        out.append(str(ans))

    return '\n'.join(out)

 ## 边缘情况

 考虑：```
1
401
```粗心的实现可能会拒绝像这样的行`"023"`因为它们都是从零开始的。 

假设在 DFS 期间我们需要带有前缀的行`"02"`。 预处理步骤包括：```
padded = "023"
```因为素数`23`长度用零填充`3`。 

算法正确处理`"023"`作为有效的素数行。 

另一个重要的例子是逐步加强对称性。 

输入：```
1
239
```选择后：```
239
307
```该算法计算：```
need = "97"
```对于第三排。 

仅限以以下开头的质数`"97"`被探索。 一排就像`"911"`永远不会被考虑，因为它会违反：```
a[1][2] = a[2][1]
```DFS 永远不会构造无效的部分矩阵。 

最后，考虑最小尺寸：```
1
11
```递归开始于`k = 1`。 所需的前缀是`"1"`。 每个两位素数开头`1`成为有效的第二行。 一次`k == n`，矩阵已完成并可计数。 

该算法自然地处理这个问题，无需任何特殊情况代码。
