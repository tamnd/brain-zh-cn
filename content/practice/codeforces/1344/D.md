 ## 解决方案
 ## 问题理解

 我们有几个项目类别，并且对于每个类别，我们知道存在多少个项目。 我们从每个类别中选择一定数量的项目放在简历中，限制条件是所选项目的总数恰好是$k$，并且我们不能从一个类别中选择比我们实际拥有的更多的东西。 

选择的分数不是线性的。 如果我们采取$b_i$类别中的项目$i$，贡献是$$b_i(a_i - b_i^2)$$因此，类别中的每个附加项目都会与未使用的项目数量相互作用，并通过以下方式引入立方惩罚：$b_i^3$。 总分是所有类别的总分，我们希望在固定总分约束下最大化它。 

关键的困难在于，由于全局约束，每个类别的决策不是独立的$\sum b_i = k$。 这将问题转化为精确分布$k$跨单位$n$“容器”，其中每个容器都有非线性利润函数。 

这些限制迫使我们进入接近线性的时间。 和$n \le 10^5$，任何尝试所有值的解决方案$b_i$明确或使用每个类别的嵌套优化太慢。 甚至$O(n \log n)$是可以接受的，但是任何涉及到所有单元的模拟的事情$k$（可能很大）是不可能的。 

一些失败案例揭示了可能出现的问题：

 总是从当前边际收益最大的类别中进行选择的贪婪策略可能看起来是正确的，但如果边际收益在没有适当处理的情况下以非单调方式交叉，则会失败。 另一个微妙的失败来自于独立对待每个类别并选择其最优的$b_i$忽略全局总和约束，这可能会违反$\sum b_i = k$。 

例如，如果一个类别有$a_i = 100$，其局部最优可能建议采用较大的$b_i$，但这可能会消耗太多预算，即使其他类别的许多小额贡献会产生更高的总分。 

该结构表明我们需要了解当我们增加时价值如何变化$b_i$渐进而不是选择$b_i$直接地。 

## 方法

 如果我们忽略耦合约束，每个类别都可以通过处理来独立优化$f_i(b) = b(a_i - b^2)$。 我们可以尝试所有$b$从$0$到$a_i$，但这是不可行的，因为$a_i$可以是$10^9$。 

更直接的暴力方法会将问题视为分布问题$k$相同的物品$n$类别并重新计算每个作业的完整函数。 即使限制于有效分布，方式的数量也是组合的$k$，即使对于很小的约束，这也是不可能的。 

关键的观察是停止思考选择最终值$b_i$，而是考虑边际收益。 如果我们增加$b_i$从$x$到$x+1$，增益为：$$\Delta_i(x) = (x+1)(a_i - (x+1)^2) - x(a_i - x^2)$$这简化为：$$\Delta_i(x) = a_i - 3x^2 - 3x - 1$$因此，每个类别都会生成边际值的递减序列，如下所示$x$增加。 问题变成：精确选择$k$所有类别的增量都具有最大边际总和。 

这是一个经典的“从许多递减序列中取出 k 个最佳项”问题。 每个类别都会贡献一个凹序列的增益，并且我们反复采用当前的最佳可用增量。 

我们可以计算每个类别的当前边际值并将它们维护在最大堆中。 每次我们选择一个增量时，我们都会更新该类别并推送其下一个边际值。 这是有效的，因为每个序列都是严格递减的，因此局部贪婪选择是全局最优的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力枚举$b_i$| 指数| O(n) | 太慢了 |
 | 边际堆贪婪 | O(k log n) 朴素，优化 O(n log k) | O(n) | 已接受 |

 剩下的问题是$k$可能会很大，所以我们必须避免一一模拟所有增量。 相反，我们对边际阈值使用二分搜索，并计算每个类别可以在该阈值之上贡献多少增量。 

## 算法演练

 ### 1. 将问题重新表述为增量收益

 我们将构建解决方案解释为从$b_i = 0$并表演$k$操作，每个操作增加一些$b_i$减 1。每个操作的值等于该增量的边际增益。 

目标变成选择$k$以最大总边际收益递增。 

### 2.推导边际收益公式

 对于固定类别$i$，假设我们已经选择了$x$元素。 下一个增益是：$$g_i(x) = a_i - 3x^2 - 3x - 1$$该函数严格递减为$x$增加，因此每个类别形成收益递减序列。 

这种单调性使得全局贪婪推理成为可能。 

### 3. 通过阈值表征最优选择

 我们没有明确选择增量，而是定义一个阈值$T$。 我们包括边际收益严格大于的所有增量$T$，并且可能有一些等于$T$完全匹配$k$。 

对于每个类别，我们解决：$$g_i(x) \ge T$$这简化为查找该序列中存在多少个有效增量。 

### 4.阈值二分查找

 我们二分查找最大阈值$T$这样增益增量的总数$\ge T$至少是$k$。 

每次检查都会计算每个类别的数量$x$满足：$$a_i - 3x^2 - 3x - 1 \ge T$$这是一个可解的二次不等式$O(1)$每个类别。 

### 5. 从阈值构建解决方案

 一旦阈值确定，我们就分配每个类别：

 - 增益严格大于的所有增量$T$- 然后使用增益等于的剩余容量$T$这准确地保证了$k$总增量。 

### 为什么它有效

 每个类别的边际增益序列严格递减，因此按全局降序选择增量相当于选择截止值以上的所有增量。 二分搜索找到一个截止点，将所有边际收益的多重集划分为选定和未选定的部分，同时保留所需的计数。 由于没有序列在减少后可以再次增加，因此跳过较高的边际增益而选择较低的边际增益并没有任何好处，因此贪婪阈值构造是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_and_sum(a, t):
    # returns total increments and how many strictly above t, and how many equal
    cnt = 0
    exact = 0
    for ai in a:
        # solve ai - 3x^2 - 3x - 1 >= t
        # 3x^2 + 3x + (1 + t - ai) <= 0
        lo, hi = 0, ai
        # find maximum x satisfying inequality
        l, r = 0, ai
        best = -1
        while l <= r:
            m = (l + r) // 2
            val = 3*m*m + 3*m + (1 + t - ai)
            if val <= 0:
                best = m
                l = m + 1
            else:
                r = m - 1
        if best >= 0:
            cnt += best + 1
            # check exact threshold hits is not needed explicitly for final construction
    return cnt

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    lo, hi = -10**18, 10**18
    while lo < hi:
        mid = (lo + hi + 1) // 2
        if count_and_sum(a, mid) >= k:
            lo = mid
        else:
            hi = mid - 1
    T = lo

    b = [0] * n
    total = 0

    for i in range(n):
        ai = a[i]
        l, r = 0, ai
        best = 0
        while l <= r:
            m = (l + r) // 2
            val = 3*m*m + 3*m + (1 + T - ai)
            if val <= 0:
                best = m
                l = m + 1
            else:
                r = m - 1
        b[i] = best
        total += best

    rem = k - total

    for i in range(n):
        if rem == 0:
            break
        if b[i] < a[i]:
            b[i] += 1
            rem -= 1

    print(*b)

if __name__ == "__main__":
    main()
```代码首先二进制搜索边际增益阈值。 功能`count_and_sum`计算如果我们采用边际增益至少为候选阈值的所有增量，每个类别将贡献多少增量。 

然后，我们使用每个类别的最大可行增量数重建基本分配。 最后，如果我们缺少确切的$k$，我们将剩余单元任意分配到仍然可以接受更多单元的类别中，这对应于恰好在阈值水平上包含一些元素。 

一个微妙的实现细节是使用整数二分搜索而不是浮点根仔细求解二次不等式。 这避免了大尺寸的精度问题$a_i$。

 ## 边缘情况

 一种重要的边缘情况是当一个类别具有极大的$a_i$与其他人相比。 幼稚的按类别优化会过度分配给它，但边际衰减确保在多次选择后，其增量增益会低于其他类别，从而迫使重新分配。 

另一个边缘情况是当$k$等于可用项目总数。 该算法必须自然地分配$b_i = a_i$而不试图超越界限。 二次不等式检查强制执行这一点，因为没有类别可以贡献比其容量更多的增量。
