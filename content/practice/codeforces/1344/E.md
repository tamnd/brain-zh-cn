 ## 解决方案
 ## 问题理解

 该系统是一棵有根的车站树，其中每个带有子节点的节点都像路由器一样，将所有传入的列车转发到其子节点之一。 换句话说，每个站点不会分割流量，而是确定性地将所有内容沿着单个传出边缘向下推送。 因此，在任何时刻，整个系统都隐含地定义了一条从站点 1 开始并继续向下到达某个叶子的活动路由。 

随着时间的推移，火车出现在根部。 每趟列车都有固定的目的地节点。 当火车通过车站时，它会立即被发送到当前交换机当时选择的任何子节点，这种情况会一直持续下去，直到它到达目的地或被困在一条永远无法到达的路径上，在这种情况下，它被认为立即爆炸。 

我们唯一的控制是，在每个整数时间，我们最多可以在火车移动之前改变一个车站的出站选择。 这些变化可用于随着时间的推移重塑活跃的根到叶路径。 

任务是选择开关更改的顺序，以便尽可能延迟第一次爆炸。 如果有可能永远正确地安排每列火车的路线，我们必须报告这一点，以及所需的最少换道次数。 否则，我们会报告第一次爆炸不可避免的最晚时间。 

这些约束强烈推动车站和列车数量的线性或近线性解决方案。 对于多达 100,000 个节点和列车，任何重新计算每个列车的路径或每个时间步进行模拟的解决方案都会立即变得太慢。 甚至$O(n \log n)$必须谨慎使用结构，任何关于火车或树操作的二次方都是不可能的。 

朴素推理的一个微妙的失败案例来自于假设我们可以使用本地决策独立地为每列火车安排路线。 例如，如果两列列车在接近的时间需要从根开始的不同分支，则天真的贪婪“仅在需要时重定向”方法可能会陷入困境，因为开关更改仅限于每单位时间一次。 

另一个棘手的情况是假设一旦火车到达正确的子树，它就保持安全。 事实上，后来的转辙变化可以改变未来列车的方向，但不会影响系统内已有的列车，这迫使我们考虑时间间隙，而不仅仅是静态可行性。 

## 方法

 关键的观察结果是，虽然结构是树，但交换机配置随时将其折叠成单个活动的根到叶路径。 每个站点都转发到一个子节点，因此从根开始只有一个可到达的延续。 

这意味着整个系统的行为就像在叶子上维护单个指针一样，其中更改开关相当于将该指针移动到不同的叶子，但成本与必须重新布线的路径量成正比。 

蛮力方法会一步一步地模拟时间。 在每个单位时间，我们将尝试所有可能的开关更改，传播所有列车，并检查是否发生爆炸。 这立即是不可行的，因为时间会增加到$10^9$，甚至仅模拟事件时间仍然需要在许多配置上进行分支。 

结构上的突破是将系统状态压缩到当前的活动叶子中。 当我们确定系统当前正在将所有列车沿着路径路由到某个叶子节点时$x$，任何将该路由转换为另一个叶子的交换机更改序列$y$其成本等于在两条根到叶路径之间选择的子节点不同的节点数。 这正是之间的距离$x$和$y$沿着根路径测量的树中，可以使用 LCA 计算。 

我们按照到达时间递增的顺序处理火车。 在连续的列车之间，我们有固定的时间预算。 在该预算内，我们每个时间单位最多可以执行一次开关更改，因此我们可以应用的结构更改总数是有限的。 

对于每列火车，我们检查其目的地是否位于当前活动的根到叶路径上。 如果是这样，则无需更改。 如果没有，我们必须将当前的叶子改造为容纳这列火车的新叶子。 此转换的成本是当前叶子和新目标叶子之间的树距离。 如果这个成本超过了下一趟列车到达之前的可用时间，那么我们就无法及时完成所需的重新配置，并且第一次爆炸就会发生在该边界处。 

贪婪策略是始终更新活动叶子以匹配最新的列车要求，因为延迟对齐只会增加未来成本，而不会增加可用时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 随着时间的推移进行全面模拟 | 不可能（最多$10^9$) | O(n + m) | 太慢了 |
 | 基于事件的叶变换与 LCA 距离 | O((n + m) log n) | O((n + m) log n) | O(n) | 已接受 |

 ## 算法演练

 我们将每次火车到达视为按时间顺序递增的事件。 系统始终维护当前的活动叶子，代表由所有交换机设置引起的从根开始的唯一路径。 

1. 将当前活动叶子初始化为输入交换机配置所暗示的初始叶子，这实际上是从根开始沿着每个节点的最后一个传出边缘形成的路径。 这给出了在进行任何调整之前使用的初始路线。 
2. 预先计算 LCA 查询的深度和二进制提升结构，以便可以快速计算任意两个节点之间的距离。 这是至关重要的，因为每个重新配置成本都取决于树的距离。 
3. 按到达时间递增的顺序处理列车。 对于每趟列车$i$，将自上一趟列车以来的时间间隔定义为可用于执行开关更改的时间量。 
4. 对于当前列车目的地$s_i$，检查它是否位于当前活动的根到叶路径上。 这可以使用 LCA 逻辑来验证：如果节点是当前叶子的祖先，则该节点位于路径上，反之亦然。 
5. 如果目的地已经与当前活动路径兼容，则无需更改开关，我们只需前往下一趟列车即可。 
6. 如果目的地不兼容，则计算从当前叶子重新配置到正确路由到的新状态的成本$s_i$。 该成本是当前叶子节点和当前叶子节点之间的树距离$s_i$。 
7. 将此成本与下一趟火车到达之前的可用时间进行比较。 如果成本超过可用时间，我们就无法在下一个事件之前完成重新配置，这就是第一次爆炸不可避免的地方。 
8. 如果成本可行，则将此成本累加到交换机更改总数中，并将当前活动叶子更新为$s_i$。 
9. Continue this process for all trains. 如果所有的转变都是可行的，就不会发生爆炸。 

关键的不变性是，在处理每个列车之后，系统正确对齐，以便当前活动叶是所有已处理列车的有效目的地，并且累积的重新配置成本与执行的开关更改数量完全匹配。 由于每个开关更改恰好修改当前根到叶结构的一个边缘，因此叶之间的转换精确地对应于沿其根路径编辑边缘，这是通过树距离捕获的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(200000)

n, m = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v, d = map(int, input().split())
    g[u].append((v, d))
    g[v].append((u, d))

trains = []
for _ in range(m):
    s, t = map(int, input().split())
    trains.append((t, s))

trains.sort()

LOG = 20
parent = [[0] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)
dist = [0] * (n + 1)

def dfs(u, p):
    for v, w in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        dist[v] = dist[u] + w
        parent[0][v] = u
        dfs(v, u)

dfs(1, 0)

for k in range(1, LOG):
    for v in range(1, n + 1):
        parent[k][v] = parent[k - 1][parent[k - 1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for k in range(LOG):
        if diff & (1 << k):
            a = parent[k][a]
    if a == b:
        return a
    for k in range(LOG - 1, -1, -1):
        if parent[k][a] != parent[k][b]:
            a = parent[k][a]
            b = parent[k][b]
    return parent[0][a]

def on_path(x, leaf):
    w = lca(x, leaf)
    return w == x or w == leaf

def get_dist(a, b):
    c = lca(a, b)
    return dist[a] + dist[b] - 2 * dist[c]

cur = 1
cur_time = trains[0][0]
ops = 0

for i, (t, s) in enumerate(trains):
    if i == 0:
        cur_time = t
        cur = s
        continue

    prev_t = trains[i - 1][0]
    gap = t - prev_t

    if not on_path(s, cur):
        cost = get_dist(cur, s)
        if cost > gap:
            print(t, ops + gap)
            sys.exit(0)
        ops += cost
        cur = s

print(-1, ops)
```DFS 构建根距离和父指针，以便可以有效地计算距离和 LCA。 功能`get_dist`将树位置转换为两个活动叶子之间的精确重新配置成本。 

关键的决策点是所需的重新配置成本和可用时间间隙之间的比较。 该比较编码系统是否可以在下一列火车施加新约束之前物理上完成所有必要的开关编辑。 

这`on_path`检查确保当当前路线已经容纳火车时我们不会浪费操作，因为在这种情况下不需要结构改变。 

## 工作示例

 ### 示例 1

 考虑一棵小的链状树，其中每个节点都有一个子节点，火车到达的目的地在更深和更浅的节点之间交替。 

| 火车 | 时间 | 目的地 | 当前叶 | 差距| 成本| 行动|
 | ---| ---| ---| ---| ---| ---| ---|
 | 1 | 2 | 4 | 4 | - | - | 初始化 |
 | 2 | 5 | 2 | 4 | 3 | 2 | 移动叶子|
 | 3 | 9 | 6 | 2 | 4 | 4 | 移动叶子|

 在这种情况下，每个过渡都适合可用的间隙。 每次重新配置都会在下一趟火车到达之前完成，因此不会发生爆炸。 

该轨迹表明可行性不仅取决于树结构，还取决于到达之间的时间间隔。 

### 示例 2

 现在考虑具有大结构跳跃的紧密间隔的到达。 

| 火车 | 时间 | 目的地 | 当前叶 | 差距| 成本| 行动|
 | ---| ---| ---| ---| ---| ---| ---|
 | 1 | 1 | 5 | 5 | - | - | 初始化 |
 | 2 | 2 | 100 | 100 5 | 1 | 8 | 失败|

 这里所需的重新配置成本立即超过可用时间间隙。 该算法正确地识别出第一次爆炸发生在时间 2，因为系统无法在第二列列车提出新要求之前完成重新布线。 

这表明爆炸时间是由第一个不可行的变换驱动的，而不是由后来的传播效应驱动的。

 ## 边缘情况

 当多列火车到达同一车站但需要完全不同的分支时，就会出现一个关键的边缘情况。 在这种情况下，一个简单的解决方案可能会尝试立即重定向每个列车，但每次一次更改的限制会强制更新序列化，并且算法通过时间间隙正确地解决了这一问题。 

另一个微妙的情况是火车的目的地已经在当前活动路径上。 该算法避免了不必要的切换，这一点至关重要，因为对此类更改进行计数会错误地增加操作计数，并可能错误地触发感知到的过载。 

最后一种情况涉及树中两片叶子相距较远的大跳跃。 基于距离的成本正确地模拟了需要多次中间开关编辑的情况，任何将其视为单个操作的尝试都会低估所需的时间并产生不正确的可行性结果。
