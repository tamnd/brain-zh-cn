 ## 解决方案
 ## 问题理解

 游戏中的每次点击都会独立地成为一次成功的点击（`O`）或错过（`X`）。 

对于一个完整的序列，我们将其分成最大连续块`O`。 如果一个块有长度`L`，它贡献`L²`到分数。 总分是这些平方块长度的总和。 

我们没有得到具体的顺序。 相反，对于每个位置`i`，我们知道概率`p[i]`表明点击成功。 所有点击都是独立的。 我们必须计算最终分数的期望值。 

第一直觉是考虑所有可能的结果。 长度序列`n`有`2^n`可能的实现，并且每个实现都有自己的分数。 通过枚举它们来计算期望是不可能的。 和`n`最多`100000`，即使存储所有结果也是荒谬的。 

约束条件`n ≤ 100000`立即表明我们需要接近线性时间的东西。 二次动态规划已经太昂贵了，因为`10^10`操作远远超出了时间限制。 任何可接受的解决方案都必须仅处理每个概率恒定的次数。 

棘手的部分是分数取决于连续成功的整个运行。 运行结束于位置`i`可能已经开始得更早了，所以局部转变并不明显。 

一些边缘情况很容易被错误处理。 

考虑：```
1
1.0
```唯一可能的顺序是`"O"`，其得分为`1`。 任何重复都必须正确初始化第一个位置。 

考虑：```
2
1.0 1.0
```唯一可能的顺序是`"OO"`，其得分为`4`， 不是`2`。 简单地将各个职位的预期贡献相加的方法会忽略连续成功之间的相互作用。 

考虑：```
3
0 1 0
```中键点击总是形成一段长度`1`，所以答案正是`1`。 任何意外地将状态带过某个位置的重复概率`0`将产生不正确的结果。 

另一个微妙的情况是：```
3
0.5 0.5 0.5
```一次跑动可以跨越多个位置，因此位置的贡献`i`取决于运行结束时的预期长度`i-1`。 这种依赖性正是解决方案必须捕获的。 

## 方法

 假设我们尝试暴力。 

对于每一个`2^n`可能的序列，我们可以计算它的概率和分数，然后添加`probability × score`到答案。 这在数学上是正确的，因为期望就是这样定义的。 

问题是结果的数量。 即使是为了`n = 50`，已经有超过一万亿个序列。 为了`n = 100000`，该方法完全不可行。 

关键的观察是我们实际上并不需要完整的运行分布。 当再处理一个位置时，我们只需要足够的信息来更新预期分数。 

想象一下一系列的成功都以当前的位置结束。 设其长度为`L`。 

如果当前单击成功，则延长长度`L-1`到长度`L`，该运行的得分贡献变化为`(L-1)²`到`L²`。 

增加量为`L² - (L-1)² = 2L - 1`。 

这种增量形式是至关重要的简化。 

我们不跟踪完整的运行，而是跟踪连续成功的当前后缀的预期长度。 当新的成功点击到达时，分数会增加`2L-1`。 由于期望是线性的，因此我们只需要期望值`L`。 

这导致了简单的线性 DP 维护：`len`，以当前位置结束的连续成功后缀的预期长度。`ans`，到目前为止累计的预期分数。 

每个概率被处理一次，给出`O(n)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 ### 状态定义

 让：`f`= 连续的预期长度`O`以当前位置结尾的后缀。`ans`= 处理当前位置后的预期得分。 

### 转移推导

 假设我们正在处理概率`p`。 

如果点击失败，则后缀长度变为`0`。 

如果点击成功则后缀长度变为之前的后缀长度加上`1`。 

因此：$$f' = p(f+1)$$因为有概率`p`我们得到`f+1`，并且有概率`1-p`我们得到`0`。 

现在考虑分数的增加。 

当成功的点击延长了新长度为`L`，运行分数增加：$$L^2-(L-1)^2 = 2L-1$$新的长度等于`f+1`以期望条件形式。 

因此，该职位贡献的预期增长为：$$p \cdot (2(f+1)-1) = p(2f+1)$$所以：$$ans' = ans + p(2f+1)$$请注意，旧值`f`更新之前必须在这里使用。 

### 编号步骤

 1. 初始化`f = 0`和`ans = 0`。 
2. 从左到右处理概率。 
3.对于当前概率`p`， 添加$$p(2f+1)$$到`ans`。 

这是如果单击成功则由于延长当前运行而导致的预期分数增加。 
4. 更新预期后缀长度：$$f = p(f+1)$$如果点击失败，后缀将变为零。 如果成功，后缀长度将增加一。 
5.所有概率处理完毕后，输出`ans`。 

### 为什么它有效

 让`L_i`表示以位置结束的连续成功后缀的随机长度`i`。 

维持变量`f`正是`E[L_i]`。 

当位置`i`成功，结束的运行长度会发生变化`L_i-1`到`L_i`。 分数增量始终为：$$L_i^2-(L_i-1)^2 = 2L_i-1$$取期望并使用期望的线性可得出：$$E[\Delta] = p_i(2E[L_{i-1}]+1)$$这正是添加到的更新`ans`。 

由于每次分数增加都会计算一次，并且`f`处理当前位置后，累计值始终等于预期后缀长度`ans`等于预期总分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(float, input().split()))

    f = 0.0
    ans = 0.0

    for prob in p:
        ans += prob * (2.0 * f + 1.0)
        f = prob * (f + 1.0)

    print("{:.15f}".format(ans))

solve()
```变量`f`存储当前连续成功后缀的预期长度。 在更新之前，我们使用其旧值来计算当前点击贡献的预期分数增加。 

顺序很重要。 公式$$ans += p(2f+1)$$使用以前一个位置结尾的后缀长度。 更新中`f`首先会错误地使用新的后缀长度和重复计算贡献的部分。 

所有计算都使用浮点数。 递归仅执行加法和乘法，因此标准双精度足以满足所需的要求`10^{-6}`准确性。 

内存使用量保持不变，因为无论什么情况，都只维护两个浮点变量`n`。

 ## 边缘情况

 考虑：```
1
0
```最初`f = 0`。 此次更新增加了`0 * (2*0 + 1) = 0`到答案，并且`f`遗迹`0`。 最终结果是`0`，与每次点击都是一次失误的事实相匹配。 

考虑：```
2
1 1
```第一次点击后，`ans = 1`和`f = 1`。 第二次点击后，增加的贡献为`1 * (2*1 + 1) = 3`，给出最终答案`4`。 这正确地代表了单次运行的长度`2`，其得分为`2²`。 

考虑：```
3
0 1 0
```第一次点击没有任何贡献并离开`f = 0`。 第二次点击贡献`1`，生产`f = 1`。 第三次单击没有任何贡献并重置后缀。 答案正是`1`，对应于一次单独的成功点击。 

考虑：```
4
1 0 1 1
```该序列是确定性的。 运行次数是`"O"`和`"OO"`, 给出分数`1² + 2² = 5`。 

该算法产生：

 | 位置 | p| f 之前 | 后|
 | --- | --- | --- | --- |
 | 1 | 1 | 0 | 1 |
 | 2 | 0 | 1 | 1 |
 | 3 | 1 | 0 | 2 |
 | 4 | 1 | 1 | 5 |

 位置二处的重置可防止后面的运行与第一个运行错误地合并。
