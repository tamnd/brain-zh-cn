 ## 解决方案
 ## 问题理解

 我们得到一个由拉丁大写字母组成的字符串和一个参数$k$。 如果子字符串不包含连续的子字符串，则该子字符串被认为是有效的$k$元音连续且不包含连续的$k$连续的辅音。 元音固定为$a, e, i, o, u$，因此每个字符都可以确定地分类为元音或辅音。 

任务是计算满足该约束的最长连续子串的长度。 

字符串长度可以大到$10^5$，这立即排除了任何显式检查所有子字符串的方法。 枚举所有子串是$O(n^2)$，甚至在线性时间内验证每一个都是$O(n^3)$，远远超出了可行的限度。 这推动我们走向具有恒定时间状态维护的线性或近线性扫描。 

一个关键的微妙之处在于，无效性取决于同一类型的连续运行，而不是绝对计数。 这使得问题本质上是局部的，但具有滑动的全局约束，当运行中断时会重置。 

当运行接近长度时出现边缘情况$k$，尤其是边界附近。 

例如，如果$k = 2$字符串是`"aaabbb"`，每个字符都是长度至少为 3 的游程的一部分，因此长度大于 2 的子串不能避免包含禁止的连续元音或辅音对。 答案变成2，因为任何单个字母或交替的单个字母都是安全的。 

另一个边缘情况是当$k = 1$。 任何元音或辅音单独已经形成长度为 1 的禁止游程，因此每个非空子串都是无效的，这迫使答案为 0。$k > 1$，理解这个边界可以澄清机制。 

第三种微妙的情况是长有效区域被翻转类型的单个字符中断。 仅跟踪元音/辅音总数的简单方法会错误地接受此类片段。 

## 方法

 暴力策略会尝试每个起始索引$l$， 延长$r$向右，并保持连续元音和辅音的计数。 每个扩展都会检查游程是否达到长度$k$已经形成。 这是正确的，因为它直接模拟约束。 

然而，每个$O(n^2)$子串可能需要最多$O(n)$如果天真地实施，在最坏的情况下进行扫描，给出$O(n^3)$。 即使进行了仔细的增量检查，仅扩展的数量也是二次的，这对于$10^5$。 

关键的观察结果是，无效性仅由相同字符类型的运行触发。 一旦我们知道所有最大连续元音段和辅音段的长度，任何子串都是有效的当且仅当它从未完全包含至少长度的段$k$不间断。 

我们不是从子串开始，而是颠倒视角。 我们可以找到所有“坏边界”，即运行达到长度的位置$k$。 任何有效的子字符串必须完全位于没有长度游程的区域内$k$被完全包含。 

因此，我们在从左到右扫描时保持当前的连续游程长度。 当跑步长度变长时$k$，任何包含当前索引之前的第一个字符的子字符串都将变得无效，因此我们向前移动左边界。 这自然会导致滑动窗口：我们维护最小的左端点，使得当前窗口不包含禁止运行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了 |
 | 滑动窗口在文字上运行 |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们从左到右处理字符串，同时维护三条信息：元音/辅音类型的当前游程长度、最后看到的字符类型以及当前窗口的最早有效起始索引。 

1. 将每个字符转换为表示元音或辅音的布尔值。 这将所有后续逻辑简化为二进制转换而不是字母表处理。 
2. 维护一个变量`run_len`它计算我们看到有多少个相同类型的连续字符在当前位置结束。 还维护`last_type`进行比较。 
3. 维护指针`left`表示以当前位置结束的有效子字符串的最小起始索引。 
4. 对于每个位置`r`，更新运行：如果当前类型匹配`last_type`, 增量`run_len`，否则重置`run_len`为 1 并更新`last_type`。 
5. 如果`run_len`变得等于$k$，开始于的子字符串`r - k + 1`并结束于`r`是被禁止的。 任何有效窗口结束于`r`不能包括整个部分，所以我们移动`left`到`r - k + 2`。 
6. 将答案更新为`max(ans, r - left + 1)`。 

步骤 5 背后的原因是窗口变得无效的唯一方法是完全包含禁止的运行。 一旦跑步达到长度$k$，必须排除在该运行之前或开始时开始并在运行结束时或之后结束的每个窗口。 

### 为什么它有效

 在每个位置$r$，该算法确保当前窗口$[left, r]$不包含任何段$k$连续的元音或辅音。 任何违规行为都必须显示为相同类型长度的连续运行$k$，一旦检测到这样的运行，所有无效窗口都会通过前进来修剪`left`刚刚超出了包括全程的最早可能起点。 这保证了每个维护的窗口都是有效的，并且每个有效窗口最终都被视为`r`扩大。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_vowel(c):
    return c in "aeiou"

def solve():
    s = input().strip()
    k = int(input())

    n = len(s)
    if n == 0:
        print(0)
        return

    ans = 0
    left = 0

    last_type = None
    run_len = 0

    for r, ch in enumerate(s):
        t = is_vowel(ch)

        if t == last_type:
            run_len += 1
        else:
            last_type = t
            run_len = 1

        if run_len >= k:
            left = max(left, r - k + 2)

        ans = max(ans, r - left + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```该实现遵循上述滑动窗口。 关键细节是更新`left = max(left, r - k + 2)`。 此表达式正确删除了仍然包含以以下结尾的完全禁止运行的最小前缀`r`。 使用`max`是必要的，因为多次重叠运行可能已经强制`left`早点转发。 

答案更新`r - left + 1`直接测量当前有效窗口的大小。

 ## 边缘情况

 一个棘手的情况是当运行恰好穿过阈值时$k$。 例如，`aaaa`和$k=3$。 在$r=2$，运行达到 3 并强制左移。 算法集`left = r - k + 2 = 1`，这意味着窗口变成`[1,2]`。 这保留了正确性，因为任何从 0 开始的窗口都将包含完全禁止的运行`"aaa"`结束于索引 2。 

另一种情况是交替角色而没有运行增长。 算法永远不会更新`left`，因此整个字符串仍然有效，这与定义匹配，因为没有形成禁止序列。 

最后一个微妙的情况是由类型切换引起的重叠运行。 由于游程长度会在类型更改时重置，因此触发移动的唯一方法是相同类型的单个连续块。 这可确保独立处理每个违规，而不会重复计算或丢失较短的无效窗口。
