 ## 解决方案
 ## 问题理解

 我们正在模拟一系列称为水手的物品的非常简单的赚钱过程。 有$n$可用的水手总数，以及每个$k$伊戈尔从剩下的人中恰好带走了一名水手。 每个水手都有一个固定的价值，纯粹由其在全球水手排序中的位置决定：第一个水手的价值$m$硬币，第二个值$m+1$，第三个值得$m+2$， 等等。 

因为水手之间没有交互作用，也没有随机性，所以唯一重要的是哪个指数排在第一位$n$在第一个过程中选择位置$k$选秀权。 由于伊戈尔每轮总是选取一名水手，并且没有超出可用范围的限制，因此该过程相当于选取第一个水手$\min(n, k)$水手们按顺序。 

输出是所有水手在这些回合中获得的值的总和。 

约束允许最多$10^5$水手和$10^5$回合。 单独迭代每个水手的解决方案已经可以接受，但任何涉及嵌套循环或重复重新计算的解决方案只有在整体严格线性的情况下才仍然可以。 任何试图在不认识算术结构的情况下逐步模拟选择的方法都会冒不必要的开销，但仍然是安全的； 真正的简化来自于认识到所选值形成连续的算术级数。 

出现微妙的边缘情况时$k = 0$。 在这种情况下，没有水手被带走，答案必须为零。 另一个边缘情况是当$k > n$，其中仅$n$水手的存在，所以这个过程有效地提前停止，并且只停止$n$条款贡献。 一个幼稚的实现总是求和$k$术语会错误地假设不存在的水手存在。 

## 方法

 如果我们直接模拟这个过程，我们就将水手一一取出并累加他们的值。 的价值$i$-第一个被抓的水手是$m + i - 1$，然后我们停止$k$步骤或用尽后$n$水手们。 这种直接方法为每个被带走的水手执行恒定量的工作，因此它运行在$O(\min(n, k))$，对于极限来说已经足够快了。 

然而，结构不是任意的，它是一个连续的算术级数，从$m$有差异$1$。 我们可以以封闭形式计算总和，而不是迭代。 如果$t = \min(n, k)$，则序列为：$$m, m+1, m+2, \dots, m+t-1$$这是一个标准算术级数，其总和可以计算为：$$t \cdot m + \frac{t(t-1)}{2}$$关键的改进是用该公式的直接计算代替迭代，将计算减少到恒定时间。

 | ---| ---| ---| ---|
 | 暴力模拟| O(min(n,k)) | O(1) | O(1) | 已接受 |
 | 算术公式 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取整数$n$,$k$， 和$m$。 这些定义了存在多少水手，有多少水手被带走，以及第一个水手的起始值。 
2.确定实际带了多少水手：set$t = \min(n, k)$。 这是必要的，因为我们不能容纳比现有更多的水手。 
3. 计算从 开始的等差数列的总和$m$与长度$t$。 不进行迭代，而是使用总和等于的恒等式$t \cdot m + \frac{t(t-1)}{2}$。 
4. 输出计算出的总和。 

### 为什么它有效

 每一步$i$，增加值正好是$m + i$，连续水手之间的增量一致为 1。 这保证了所取的值形成完美的算术级数，没有间隙或重新排序。 因为我们正好取第一个$t$水手们按顺序排列，没有排列或选择效应会改变顺序。 因此，算术级数的求和公式与该过程的任何有效执行的累积结果完全匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, m = map(int, input().split())
    
    t = min(n, k)
    
    # sum of m + (m+1) + ... + (m+t-1)
    # = t*m + (0 + 1 + ... + t-1)
    # = t*m + t*(t-1)//2
    ans = t * m + t * (t - 1) // 2
    
    print(ans)

if __name__ == "__main__":
    solve()
```代码首先读取输入值并立即将问题规模缩小到$t = \min(n, k)$，确保我们只考虑有效的选择。 然后直接应用算术级数公式。 无减法公式避免了任何浮点运算，并完全依赖于整数运算，这在 Python 的无界整数下是安全的。 

一个常见的陷阱是忘记夹紧$k$经过$n$，这会错误地假设水手超出$n$存在。 另一种方法是用除法而不是整数除法来实现求和，这可能会在其他语言中引入浮动错误。

 ## 边缘情况

 对于$k = 0$，算法集$t = 0$，立即产生总和$0$因为公式中的两项都消失了。 例如，输入$1\ 0\ 10$导致$t=0$， 因此$0 \cdot 10 + 0 = 0$。 

什么时候$k > n$，夹紧步骤确保我们只对现有的水手求和。 例如，$n=3, k=10, m=5$产量$t=3$，生产$5+6+7=18$。 任何天真的循环$k$会尝试访问不存在的水手，结果要么崩溃，要么计数过多。 

什么时候$n = 1$，无论什么，级数都会崩溃为单个值$k$。 为了$n=1, k=100, m=42$，结果总是$42$， 自从$t=1$公式简化为$1 \cdot 42 + 0$。
