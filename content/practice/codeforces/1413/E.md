 ## 解决方案
 ## 问题理解

 我们反复对敌人施法。 

每个演员立即交易`a`损害。 之后，同样的施法可以治疗敌人`b`每秒的健康状况`c`秒。 演员阵容每年都会发生`d`由于冷却时间，所有效果都会叠加。 

如果在某个整数时刻，所有施法的总累积效果使其生命值变为负值，则敌人就会死亡。 由于同一时刻发生的每一个健康变化都会一起应用，所以真正重要的是任何时候达到的最大总伤害减去治疗效果。 

对于每个测试用例，我们必须找到仍然可以杀死的最大敌人生命值。 如果累积的伤害可以无限增长，那么任何生命值最终都是可杀死的，答案是`-1`。 

测试用例的数量为`10^5`，所以任何涉及随着时间的推移进行模拟的事情都是不可能的。 参数本身可以达到`10^6`，这意味着答案可能是`10^12`，因此需要 64 位算术。 

挑战在于许多先前施法的治疗效果重叠。 直接的时间线模拟可能需要处理数百万或数十亿个时刻，这远远超出了限制。 

一些边缘情况值得特别关注。 

考虑：```
a = 1, b = 2, c = 3, d = 4
```该法术的治疗时间只有三秒，但冷却时间为四秒。 每次施法都会在下一次施法发生之前完成所有治疗。 达到的最佳伤害就是第一次攻击，所以答案是`1`。 

现在考虑：```
a = 239, b = 21, c = 11, d = 3
```在这里，每个施法造成的伤害比施法之间引入的总额外治疗量还要多。 累积伤害永远增长，所以答案是`-1`。 

另一个微妙的情况是：```
a = 4, b = 3, c = 2, d = 1
```一个幼稚的实现可能只考虑每次施法的净伤害并得出答案很大的结论。 事实上，重叠的治疗很快就会抵消未来的施法。 正确答案是`5`，在特定的中间时间实现。 

## 方法

 最直接的方法是模拟该过程。 

我们有时可以投`0, d, 2d, ...`，跟踪所有主动治疗效果，并计算每次事件后的总伤害减去治疗效果。 达到的最大值就是可以杀死的最大生命值。 

这在概念上是有效的，因为答案正是有史以来达到的最大累积伤害。 不幸的是，持续时间可以任意长。 当损害不断增加时，就没有有限的停止点。 即使在有限的情况下，参数高达`10^6`使逐个事件的模拟变得过于昂贵。 

关键的观察是我们不需要整个时间表。 

假设有时会发生强制转换：```
0, d, 2d, 3d, ...
```让我们检查一下之后的累积效应`k`-th 演员。 

每个新演员都有贡献`+a`。 

在连续施法之间，会发生一些愈合。 多少？ 

石膏在接下来的时间内愈合`c`秒。 由于演员阵容的间隔为`d`秒，特定演员仍然活跃```
ceil(c / d)
```施法间隔。 

计算施法时刻主动愈合的一种更简洁的方法是观察施法之间的情况`i-1`并投射`i`，每一个之前的法术，其治疗时间仍然覆盖该间隔贡献`b*d`康复。 

此类活跃法术的数量最终稳定在```
m = floor((c - 1) / d)
```因为一个咒语会影响下一个咒语`m + 1`间隔。 

经过足够的施法后，每次额外的施法都会改变累积伤害```
a - b * (m + 1)
```这是```
a - b * ceil(c / d)
```自从```
ceil(c/d) = floor((c-1)/d) + 1.
```如果该数量为正，则累积损害将永远增长。 任何生命值最终都会被杀死，所以答案是`-1`。 

否则序列最终会减少，这意味着最大值出现在早期的演员阵容中。 

让```
k = floor((c - 1) / d)
```那么最好的时刻就是在`(k+1)`-st 演员。 到那时，每次新施法都会使累积伤害增加```
a - b * i
```为了增加价值`i`。 

将这些收益相加得出```
answer =
a + (a-b) + (a-2b) + ... + (a-kb)
```这简化为```
(k+1)a - b * k(k+1)/2.
```这个值就是可以杀死的最大生命值。

 ## 算法演练

 1. 计算```
k = floor((c - 1) / d).
```这是之前法术仍可提供治疗效果的施法间隔数。 
2. 检查是否```
a > b * (k + 1).
```这是重叠模式稳定后再添加一个铸件所带来的长期收益。 
3. 如果不等式成立，则打印`-1`。 

累积伤害无限制地增加，因此生命值任意大的敌人最终都可以被杀死。 
4. 否则计算```
(k + 1) * a - b * k * (k + 1) / 2.
```这是迄今为止达到的最大累积伤害。 
5. 输出该值。 

### 为什么它有效

 让`D(n)`是紧接着发生后的累积伤害减去治疗量`n`-th 演员。 

第一个演员贡献`a`。 

随后的每个演员都会添加另一个`a`，但也会受到先前激活法术产生的治疗效果。 在重叠模式稳定之前，施法之间添加的治疗效果会精确地增加`b`每一步。 后`k+1`存在活跃间隔，增加的治疗效果恒定在`b(k+1)`。 

因此连续的差异`D(n)`形式：```
a,
a-b,
a-2b,
...
a-kb,
a-(k+1)b,
a-(k+1)b,
...
```如果最终的常数差为正，则序列将永远增长。 否则，在达到对应的项后，序列将变为非增`a-kb`，因此它的最大值正好在该点获得。 对算术级数求和即可得出上述公式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        a, b, c, d = map(int, input().split())

        k = (c - 1) // d

        if a > b * (k + 1):
            ans.append("-1")
        else:
            res = (k + 1) * a - b * k * (k + 1) // 2
            ans.append(str(res))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```实现直接遵循数学推导。 

价值```
k = (c - 1) // d
```捕获受法术治疗影响的额外施法间隔数。 

条件```
a > b * (k + 1)
```检查累积损伤序列的稳定斜率是否为正。 如果是，则答案是无界的，我们打印`-1`。 

否则，我们评估算术级数的封闭形式和。 Python 整数自动处理大于 64 位的值，尽管带符号的 64 位整数也足以解决此问题。 

最常见的错误是使用`c // d`而不是`(c - 1) // d`。 施法后一秒开始治疗并持续到底`c`秒，因此正确的重叠计数源自`ceil(c/d)`，等于`(c - 1)//d + 1`。

 ## 边缘情况

 ### 完全没有重叠

 输入：```
1
5 2 3 10
```我们得到：```
k = (3 - 1) // 10 = 0
```公式变为：```
(0+1) * 5 = 5
```每次施法都在下一次施法开始之前很久就完成了治疗。 最好的伤害就是第一击。 

输出：```
5
```### 长期斜率恰好为零

 输入：```
1
6 3 2 1
```我们有：```
k = 1
a = 6
b(k+1) = 6
```增益的顺序是：```
6, 3, 0, 0, ...
```累计伤害达到：```
6 -> 9 -> 9 -> 9 ...
```最大值是有限的并且等于`9`。 

输出：```
9
```此案例捕获了错误使用的解决方案`>=`而不是`>`在无界性测试中。 

### 无限增长

 输入：```
1
239 21 11 3
```我们计算：```
k = 3
b(k+1) = 84
```自从```
239 > 84
```每次足够晚的施法都会增加累积伤害。 没有有限的最大值。 

输出：```
-1
```这种情况捕获的解决方案始终应用算术级数公式，而不首先检查序列是否无界。
