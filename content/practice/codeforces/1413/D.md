 ## 解决方案
 ## 问题理解

 我们得到了一个按时间顺序排列的在一个空的展示柜上执行的操作日志。 有两种类型的事件。 一个事件插入一个具有某些未知值的新手里剑，另一个事件删除当前存在的最小值，并准确报告删除的值。 

我们被告知，从 1 到 n 的所有值在删除事件中只出现一次，并且恰好有 n 次插入。 任务不是盲目模拟，而是确定是否存在对插入事件的任何值分配，使得每次删除最小值都与多重集演化一致。 如果可能的话，我们还必须输出一个有效的插入事件赋值。 

关键的困难是插入没有标记。 我们不知道每个“+”处插入哪个值，我们必须分配值，以便每当出现“- x”时，x 就是当时可用的最小值。 

约束 n 高达 100000 意味着任何带有回溯的二次甚至 n log n 重度模拟如果重复尝试分配都会太慢。 我们需要一个维护当前可用项目集的单遍结构和一个贪婪地构造一致分配的策略。 

当在没有可用项目的情况下进行删除时，会出现微妙的失败情况。 例如，第一个事件是删除，它立即无效，因为还没有插入任何内容。 

当删除 x 时算法允许小于 x 的元素保留在结构中时，会出现另一种失败情况。 例如，如果插入 1 但在删除 2 之前没有删除，则该序列无效，因为在 1 仍然存在的情况下 2 不可能是最小值。 

一个不太明显的边缘情况是，在任何删除之前发生多次插入，我们必须决定以与未来删除一致的方式为这些插入分配哪些值。 按插入顺序分配值而不考虑未来约束的幼稚策略将会失败。 

## 方法

 暴力方法会尝试将 1 到 n 的排列分配给插入位置，然后模拟每个候选分配的过程。 对于每个“-x”，我们将检查 x 是否确实是当前多重集的最小值。 这需要构建并检查所有赋值排列，导致 n! 如果我们使用多重集，则每次模拟的成本为 O(n log n)。 即使对于较小的 n，这在天文数字上也是不可行的。 

关键的观察是约束仅指删除时的最小元素。 这表明我们应该考虑受未来最低要求约束的类似堆栈的结构。 我们可以推迟决定，直到被迫分配一个值，而不是立即决定插入值。 

我们按顺序处理事件，维护当前插入但未分配的槽的结构。 当我们遇到x的删除时，我们知道x一定是当前可用的最小值。 因此，在所有仍处于“开放”状态的未分配插入槽中，x 必须分配给最近的插入，该插入仍然可能是 x，否则会更早地强制使用较小的值并违反最小约束。 

这导致了贪婪的构造：我们维护一堆尚未分配值的“+”事件的位置。 当我们看到“- x”时，我们将 x 分配给最近未分配的“+”，并从堆栈中删除该槽。 如果在任何时候我们尝试删除但不存在未分配的插入，则该序列是不可能的。 

这是有效的，因为最后一个未分配的插入始终是最受约束的：它是最接近当前时刻的插入，因此必须吸收当前最小的所需值。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!·n log n) | O(n!·n log n) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们从左到右处理事件序列，同时维护尚未分配值的插入事件索引堆栈。 

1. 按顺序读取事件，记录所有“+”操作的位置。 每次我们看到“+”时，我们都会将其索引压入堆栈，因为它代表一个必须接收某些值的未来槽。 
2.当我们遇到“-x”事件时，我们检查堆栈是否为空。 如果它为空，则没有可用于生成 x 的插入，因此该序列无效。 
3. 否则，我们从堆栈中弹出最近未分配的插入索引，并为其分配值 x。 这确保 x 绑定到最近引入的占位符。 
4. 我们继续此过程，直到处理完所有事件。 
5. 处理完所有事件后，我们按照插入位置出现的顺序输出值的分配。 如果在任何时候我们删除失败，我们都会输出“NO”。 

为什么有效：在处理 x 的删除时，x 保证是当前展示中的最小元素。 任何尚未赋值的插入都代表一个元素，其精确值仍然灵活，但所有此类元素必须严格大于所有先前删除的与序列保持一致的元素。 将 x 分配给最近的插入可确保较早的插入不会被迫在以后取较小的值，因为较早的插入在结构中具有较长的生命周期，因此有更多机会受到未来最小删除的约束。 这种贪婪的责任反转保留了当前多重集始终可以一致扩展的不变性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    ops = []
    plus_pos = []
    
    for i in range(2 * n):
        line = input().strip()
        if line == '+':
            ops.append(('+', None))
            plus_pos.append(i)
        else:
            _, x = line.split()
            ops.append(('-', int(x)))
    
    ans = [0] * (2 * n)
    stack = []
    ptr = 0
    
    for i, (t, val) in enumerate(ops):
        if t == '+':
            stack.append(i)
        else:
            if not stack:
                print("NO")
                return
            pos = stack.pop()
            ans[pos] = val
    
    print("YES")
    res = []
    for i, (t, _) in enumerate(ops):
        if t == '+':
            res.append(str(ans[i]))
    print(" ".join(res))

if __name__ == "__main__":
    solve()
```该解决方案存储插入事件的索引，以便稍后在其相应的删除强制做出决定时为每个“+”分配一个值。 堆栈确保我们始终首先分配最近的开放插入，这对于保持可行性至关重要。 

数组`ans`记录分配给每个插入位置的值。 处理完所有事件后，我们只需按插入顺序提取值即可形成所需的输出。 

一个常见的陷阱是忘记分配必须与“+”事件完全一一对应。 另一种方法是尝试直接模拟多重集，但由于我们不知道初始分配结构而失败。

 ## 边缘情况

 第一种边缘情况是立即发生的删除。 该算法通过在尝试弹出之前检查可用插入堆栈是否为空来处理此问题。 在输入中`- 1`，堆栈在第一步是空的，因此算法正确地拒绝了该序列。 

另一个边缘情况是所有插入都发生在删除之前。 在三个“+”后跟“- 3 - 2 - 1”的序列中，堆栈增长到大小三，然后以相反的顺序消耗。 每次弹出都会将当前删除值分配给最近的插入，从而生成满足所有最小约束的一致映射。 

第三种边缘情况涉及交替操作。 在“+ - 1 + - 2”中，第一个插入立即被消耗，然后第二个插入稍后被消耗。 堆栈确保局部性，因此每次删除始终与最新的可用插入匹配，即使在交错的情况下也能保持有效性。
