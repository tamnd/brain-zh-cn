 ## 解决方案
 ## 问题理解

 我们得到一个包含小写字母和通配符的字符串。 每个通配符都可以独立地替换为任何小写字母。 选择替换后，结果字符串是固定的，然后我们考虑通过排列其字符可以获得的所有不同字符串。 

对于任何完全具体的字符串，不同排列的数量仅由其字符频率决定。 如果一个字符出现多次，交换相同的字母不会创建新的字符串，因此计数是基于频率计数的多项式系数。 

这里的过程是两层的。 首先我们随机选择如何替换通配符，统一所有$26^{k}$作业，如果有$k$问号。 然后对于结果字符串，我们计算不同排列的数量。 任务是计算这个排列计数的期望值，以一个大素数为模。 

约束允许字符串的长度最多为 1000，最多有 500 个测试用例，总长度为 5000。这排除了任何枚举问号填充或枚举最终字符串的排列的方法。 即使每个测试用例的二次工作也很好，但通配符数量呈指数级增长是不可能的。 

一个微妙的边缘情况是存在许多问号。 一个天真的想法是独立处理每个填充字符串并计算其排列计数，但这隐藏了真正的结构：许多填充共享相同的多组频率，并且直接枚举双重计数严重。 另一个陷阱是尝试模拟每次填充的排列计数，这已经是$O(n!)$在自然界中是完全不可行的。 

真正的挑战是期望超过分配，但数量仅取决于最终频率计数，因此我们需要一种方法来计算由随机独立字母分配引起的平均多项式系数。 

## 方法

 蛮力解释很简单：迭代所有$26^{k}$填充问号的方法，计算每个完整字符串的字符频率，然后使用阶乘和频率分母计算不同排列的数量。 即使我们预先计算阶乘，每次评估都会花费$O(n)$，导致$O(n \cdot 26^k)$，这远远超出了限制，当$k$甚至是中等大小。 

关键的见解是扭转我们对排列的看法。 我们可以考虑先选择一个排列，然后询问随机填充是否使其以结构化方式有效，而不是生成填充然后计算排列。 另一种等效且更直接的路径是用每个字母独立的贡献来表达期望的多项式系数。 

修复最终的多组字母计数$c_1, c_2, \dots, c_{26}$。 不同排列的数量为：$$\frac{n!}{\prod c_i!}$$随机性仅影响问号贡献的字母数。 每个问号独立地为均匀随机的字母贡献一个单位，因此最终计数是确定性基本计数和多项式随机向量的总和。 

我们想要：$$\mathbb{E}\left[\frac{n!}{\prod c_i!}\right]$$分解因素$n!$，因为它在所有填充物中都是恒定的：$$n! \cdot \mathbb{E}\left[\prod \frac{1}{c_i!}\right]$$困难在于$c_i$通过所有问号分布在字母之间的约束相互关联。 我们没有直接使用随机变量的阶乘，而是使用经典的组合技巧来扩展期望：通过对问号的贡献生成函数来独立地处理每个字母。 

对于每个字母$i$，假设它已经出现$a_i$字符串固定部分的时间。 让$x_i$有多少个问号变成字母$i$。 然后：$$c_i = a_i + x_i$$我们需要对所有分布求和$x_i$和$\sum x_i = k$，按多项式概率加权：$$\frac{k!}{x_1! \cdots x_{26}!} \cdot \frac{1}{26^k}$$所以期望就变成了：$$\frac{n!}{26^k} \sum_{x_1+\cdots+x_{26}=k} \prod_{i=1}^{26} \frac{1}{(a_i + x_i)!} \cdot \frac{k!}{x_1! \cdots x_{26}!}$$现在结构由字母分隔，我们可以使用字母上的 DP 和分配的问号数量来计算。 每个州都会跟踪已处理的信件中分配了多少个问号。 

我们定义：$$dp[i][j]$$作为使用第一个的贡献$i$字母与完全$j$分配了问号。 过渡有多少个问号$t$去信$i$，乘以：$$\frac{1}{(a_i + t)! \cdot t!}$$最后我们乘以$n! \cdot k! / 26^k$。 这个DP很小：26个字母，最多1000个问号，所以$O(26 \cdot k^2)$通过跨测试用例的优化或预计算重用，每个测试是可以接受的。 

这会将字符串的概率期望转换为 26 个有界维度的结构化卷积。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(26^k \cdot n)$|$O(n)$| 太慢了 |
 | 字母和计数的最佳 DP |$O(26 \cdot k^2)$|$O(k)$| 已接受 |

 ## 算法演练

 1. 计算每个字母在字符串中出现的次数，并计算存在多少个问号。 这将固定结构与随机性分开。 
2. 预先计算阶乘直至最大可能的字符串长度。 我们需要排列计数的分子和分母的阶乘。 
3. 计算全局乘法因子$n! \cdot k! / 26^k$。 这$k!$由分布问号的多项式加权产生。 
4. 构建一个 DP 数组，其中每个状态代表处理一个字母前缀并在其中分配一定数量的问号。 
5. 用第一个字母初始化DP。 对于固定字母，请尝试分配$t$给它打上问号。 每个选择都会贡献一个权重：$$\frac{1}{(a_i + t)! \cdot t!}$$乘以先前状态的组合转变。 
6. 迭代所有26个字母，逐层更新DP，使得处理完字母后$i$，所有问号分布在第一个$i$字母被占。 
7. 处理完所有字母后，DP值正好为$k$分配的问号是所有有效分布所需的总和。 
8. 将DP结果乘以之前计算的全局因子，得到期望值模$10^9+7$。 

### 为什么它有效

 DP 将问号在字母之间的每种可能的分配精确地枚举一次，并且每种分配都按正确的多项式概率进行加权。 由于排列计数仅取决于最终频率向量并分解为独立的每个字母阶乘项，因此每个分配的贡献分解为字母的乘积。 DP 只是一种对所有有效向量求和的结构化方法$(x_1, \dots, x_{26})$具有正确的组合权重，因此它与期望的定义完全匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
MAXN = 1000

# factorials
fact = [1] * (MAXN + 1)
invfact = [1] * (MAXN + 1)

for i in range(1, MAXN + 1):
    fact[i] = fact[i - 1] * i % MOD

invfact[MAXN] = pow(fact[MAXN], MOD - 2, MOD)
for i in range(MAXN, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def solve(s):
    n = len(s)
    cnt = [0] * 26
    k = 0

    for ch in s:
        if ch == '?':
            k += 1
        else:
            cnt[ord(ch) - 97] += 1

    # dp[j] = sum of contributions after processing letters so far
    dp = [0] * (k + 1)
    dp[0] = 1

    for i in range(26):
        ndp = [0] * (k + 1)
        a = cnt[i]

        for used in range(k + 1):
            if dp[used] == 0:
                continue
            base = dp[used]
            for add in range(k - used + 1):
                val = base * invfact[a + add] % MOD * invfact[add] % MOD
                ndp[used + add] = (ndp[used + add] + val) % MOD

        dp = ndp

    ways = dp[k]

    # multiply global factor: n! * k! / 26^k
    ans = fact[n] * fact[k] % MOD
    ans = ans * pow(26, MOD - 1 - k, MOD) % MOD
    ans = ans * ways % MOD

    return ans

t = int(input())
for _ in range(t):
    s = input().strip()
    print(solve(s))
```该解决方案首先修复阶乘表，因为排列和多项式展开都依赖于重复的阶乘反演。 然后，每个测试用例将固定字母与问号分开。 

DP 在指定的问号总数上使用一维。 对于每个字母，它会分配额外的问号并乘以代表最终频率损失的逆阶乘项。 第二个逆阶乘对应于为该字母分配问号的多项式权重。 

最终的缩放因子结合了排列分子$n!$, 多项式归一化$k!$和概率归一化$26^{-k}$。

这验证了算法正确地分离结构结果而不是枚举排列。 

### 示例 2：`??`这里$k = 2$，并且所有碱基计数均为零。 

| 信| 用过的 ？ | DP洞察|

 DP 枚举字母间两个相同随机分配的所有分割。 它捕获两个字母相同与不同的情况，并正确权重$1/26^2$分布。 最终结果符合任何分配仅取决于碰撞模式而不是顺序的对称性。

 ## 边缘情况

 一个特殊情况是字符串没有问号。 在这种情况下，DP 简化为单个确定性频率向量，并且答案必须等于$n! / \prod c_i!$。 该算法处理这个问题是因为$k = 0$，所以 DP 永远不会分支，最终的缩放就变成了$n! \cdot 1$。 

另一种情况是所有字符都是问号。 那么所有碱基计数都为零，并且 DP 成为 26 个字母的纯多项式分布。 对称性确保只有碰撞结构才重要。 该算法自然地处理这个问题，因为所有阶乘惩罚仅来自分配的计数，并且每个分配都被统一处理。 

第三种情况是当一个字母占据固定部分并且所有问号必须分布在它周围时。 DP 正确地累积了高频阶乘分母的大量贡献，防止了朴素计数逻辑的溢出。
