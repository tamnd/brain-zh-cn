 ## 解决方案
 ## 问题理解

 我们有两个长度相等的数组，并且允许我们修改第一个数组，直到它与第二个数组相同。 成本模型有两部分。 First, each unit increment or decrement on any position costs one operation, so changing a value from`x`到`y`成本`|x - y|`。 其次，有一个可选的结构操作：我们可以选择一个固定长度的连续段`k`并向左旋转一次。 旋转之后，段内的元素会循环排列，而外部的所有元素都保持在原位。 

任务是找到将第一个数组转换为第二个数组所需的最小总操作成本，其中我们可以从不使用旋转，或者在任何有效的长度段上仅使用一次`k`。 

这些约束清楚地表明，每个测试用例的解决方案必须接近线性。 所有测试的总大小最多为`2 · 10^5`，所以任何平方`n`每次测试立即不可行。 甚至一个`O(n log n)`每个测试只有在仔细实施的情况下才是可接受的，但这里的结构强烈建议`O(n)`或者`O(n log n)`解决方案只需简单地传递数组即可。 

一种简单的方法是尝试每一个可能的旋转段，并从头开始重新计算完整的转换成本。 这在小例子上已经失败了。 

例如，假设`n = 5`和`k = 3`。 蛮力方法会尝试分段`[1,3]`,`[2,4]`,`[3,5]`，每次应用轮换，并重新计算总成本。 每次重新计算是`O(n)`, 给予`O(n^2)`全面的。 这太慢了`n`达到`2 · 10^5`。 

当值很大但结构化时，例如当`a`和`b`除了旋转可以完美对齐值的小窗口之外，其他都是相同的。 简单的方法可能会忽略旋转带来的改进仅取决于局部变化，而不是全局重新计算。 

## 方法

 如果我们忽略旋转，问题就完全简单了。 每个位置都是独立的，成本只是相应元素之间的绝对差之和。 这给出了一个基线答案。 

困难来自于单个允许的循环移位。 关键的观察结果是，此操作仅排列一个大小窗口内的值`k`。 窗口外的所有内容都保持不变，因此只有该窗口内的成本贡献会受到影响。 

蛮力的想法是尝试每一个可能的长度段`k`，模拟旋转，并从头开始重新计算总成本。 这在概念上是有效的，因为只有`n - k + 1`选择，但每次模拟都会花费`O(n)`，导致`O(n^2)`每个测试用例。 

改进来自于将数组中未受影响的部分与受影响的窗口分开。 在所选段之外，旋转前后对成本的贡献是相同的。 在段内部，旋转仅改变`a`元素与哪个配对`b`位置。 这使我们能够用少量预先计算的总和来表达新的成本。 

我们不是重新计算所有内容，而是预先计算基线失配成本，然后为每个窗口计算如果我们在其中应用旋转，成本将如何变化。 这将线性预处理后的每个候选评估减少到恒定时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（模拟每次旋转并重新计算全部成本）| O(n²) | O(1) | O(1) | 太慢了 |
 | 基于前缀的窗口评估 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们首先计算保持数组不变的成本。 这只是之间的绝对差异之和`a[i]`和`b[i]`。 

接下来，我们分析如果对一个段应用旋转会发生什么`[l, r]`在哪里`r = l + k - 1`。 

1. 预先计算基线失配数组`base[i] = |a[i] - b[i]|`。 这表示不使用轮换时每个位置对总成本的贡献。 
2. 定义辅助不匹配数组`shift_cost[i] = |a[i+1] - b[i]|`用于窗口内元素向左移动的位置。 这对应于旋转段中除最后一个位置之外的每个位置所发生的情况，因为旋转后，位置`i`接收价值`a[i+1]`。 
3. 对于固定窗口`[l, r]`，计算旋转后窗口内的成本。 对于职位`l`到`r-1`，成本变为`|a[i+1] - b[i]|`，对于位置`r`，成本变为`|a[l] - b[r]|`。 
4. 使用前缀和有效地表达这一点。 总和结束了`shift_cost[l .. r-1]`查询的时间复杂度为 O(1)，最后一项直接计算。 
5. 减去同一窗口的原始基线成本，即为`base[l .. r]`，也可通过前缀和获得。 
6. 差值给出了在以下位置应用轮换的净收益或损失：`[l, r]`。 
7. 计算所有有效值`l`并取所有窗口中的最小值。 最终的答案是不采取任何行动和应用最佳轮换之间的最小值。 

### 为什么它有效

 关键的不变量是，只有所选段内的索引可以改变它们与元素的配对`b`。 段外的每个索引在轮换之前和之后贡献完全相同的成本。 在段内部，每个位置恰好接收一个新值，并且该映射是完全确定性的：单个左循环移位对应于长度的固定排列`k`。 由于成本函数在索引之间是可分离的，因此总成本差异分解为独立的位置差异之和，可以使用前缀和进行聚合。 这保证了独立评估每个部分就足够了，并且不会错过全局交互。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        base = [abs(a[i] - b[i]) for i in range(n)]
        pref_base = [0] * (n + 1)
        for i in range(n):
            pref_base[i + 1] = pref_base[i] + base[i]

        # shift contribution: a[i+1] matches b[i]
        shift = [0] * (n - 1)
        for i in range(n - 1):
            shift[i] = abs(a[i + 1] - b[i])

        pref_shift = [0] * (n)
        for i in range(n - 1):
            pref_shift[i + 1] = pref_shift[i] + shift[i]
        pref_shift[n - 1] = pref_shift[n - 2] if n > 1 else 0

        best_delta = 0

        if k == 1:
            # rotation does nothing
            print(pref_base[n])
            continue

        for l in range(0, n - k + 1):
            r = l + k - 1

            # cost of shifted positions l..r-1
            shifted_sum = pref_shift[r] - pref_shift[l]

            # last position uses a[l]
            last_cost = abs(a[l] - b[r])

            new_cost = shifted_sum + last_cost
            old_cost = pref_base[r + 1] - pref_base[l]

            delta = new_cost - old_cost
            best_delta = min(best_delta, delta)

        print(pref_base[n] + best_delta)

if __name__ == "__main__":
    solve()
```该实现首先计算基线成本并存储前缀和，以便可以在恒定时间内查询任何范围成本。 第二个前缀数组是为移位对齐构建的，表示如果每个位置接收到数组中的下一个元素，则会花费多少成本。 

旋转窗口的所有有效起始位置上的循环会在恒定时间内计算该窗口的新成本。 移位的部分取自预先计算的前缀，而窗口的最后一个元素则单独处理，因为它环绕到段的第一个元素。 

答案跟踪所有部分的最佳改进，包括根本不应用任何旋转的可能性。

 ## 边缘情况

 一个重要的边缘情况是当`k = 1`。 在这种情况下，允许的旋转是无操作的，因此答案必须减少到绝对差之和。 该算法通过立即返回基线成本来显式处理此问题，避免不必要的前缀计算，否则会在移位数组中引入相差一错误。 

另一种边缘情况发生在`k = n`。 这里，旋转适用于整个数组，并且算法正确地评估覆盖所有索引的单个窗口。 环绕项仍然可以正确处理，因为数组的第一个元素用作旋转后的最终位置。 

第三种情况是最优解根本不使用旋转。 这是通过将最佳增量初始化为零并且仅在找到严格更好的配置时才更新它来处理的，从而确保即使每次旋转都会增加成本，基线解决方案仍然有效。
