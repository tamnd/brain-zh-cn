 ## 解决方案
 ## 问题理解

 我们得到了一条路径上的一系列海拔高度，然后我们从左到右穿过它。 任务是计算这个序列中出现了多少次“爬山”。 

登山是至少三个连续点的任何连续部分，其中每一步高度都严格增加。 一旦严格递增的段开始，只要每个下一个值大于前一个值，它就会继续。 如果持续增加超过三个点，仍然算作单座山，而不是多个重叠的山。 关键思想是我们正在计算长度至少为 3 的最大严格递增游程。 

输入大小最多为 1000，这足够小，O(N²) 解决方案仍然可以轻松通过。 然而，由于结构是线性的和局部的，我们应该期望 O(N) 扫描就足够了。 

一些边缘情况在这里很重要。 单一的增加台阶不足以形成一座山。 例如，在`[1, 2]`，不会计算任何内容，因为游程长度仅为 2，即使它在增加。 

如果一个序列增加然后停止增加，如果它足够长，我们只需计算一次。 例如，`[1, 2, 3, 4, 2]`只包含一座山，而不是像这样多个重叠的山`[1,2,3]`和`[2,3,4]`。 

扁平的价值观可以打破一座大山。 例如，`[1, 2, 2, 3, 4]`重置高原上的增加运行，因此我们不能将其视为单个连续爬升。 

## 方法

 思考该问题的一种直接方法是检查每个可能的起始索引，并在序列严格递增的情况下向前扩展。 每次到达增加停止的点时，我们都会检查线段长度是否至少为 3，如果是则计数。 

这种蛮力方法之所以有效，是因为每座山都是一个最大严格递增子数组，因此从每个位置扫描并扩展可确保我们不会错过任何候选者。 然而，这是浪费的：对于每个起始位置，我们可能会向前扫描最多 O(N) 个元素，从而在最坏的情况下导致 O(N²) 次操作，例如完全递增的数组。 

关键的观察是我们不需要在每个索引处重新启动扫描。 相反，我们只需要跟踪连续的严格递增运行。 每个游程可以处理一次：当我们检测到序列停止增加时，我们最终确定游程长度并决定它是否形成一座山。 

这将问题变成了单遍，我们保持当前增加的条纹的长度，并在条纹中断时重置它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N²) | O(1) | O(1) | 太慢了 |
 | 单程追踪 | O(N) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从左到右扫描数组，同时保持当前严格递增段的长度。 

1. 从计数器开始`cnt = 1`代表当前增加的游程长度。 

这是可行的，因为单个元素基本上就是一个长度游程。 
2. 对于每个索引`i`从 1 到 N−1，比较`a[i]`和`a[i−1]`。 

如果`a[i] > a[i−1]`，通过增加来延长当前运行时间`cnt`一个。 

这保留了以下属性`cnt`始终表示当前严格递增后缀的长度。 
3.如果`a[i] <= a[i−1]`，财产损失不断增加。 在重置之前，检查我们刚刚结束的运行的长度是否至少为 3。如果是，则增加答案。 

然后重置`cnt = 1`因为新的运行从位置开始`i`。 
4. 完成循环后，我们必须对最后一次运行执行最终检查，因为数组可能会在仍在增加的同时结束。 如果`cnt >= 3`，算作一座山。 

它之所以有效，是因为每个严格递增的段在其边界处都被恰好处理一次。 该算法永远不会分割有效的山，因为它仅在递增属性被破坏时才最终确定一个分段。 每个最大递增游程都是唯一标识的，其长度完全决定是否被计数。 没有重叠或部分片段被重复计算，因为我们永远不会在有效的增加条纹内重新开始。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

ans = 0
cnt = 1

for i in range(1, n):
    if a[i] > a[i - 1]:
        cnt += 1
    else:
        if cnt >= 3:
            ans += 1
        cnt = 1

if cnt >= 3:
    ans += 1

print(ans)
```该解决方案为当前的增加趋势保留一个运行计数器。 每次顺序被打破时，我们都会决定该连胜是否符合山脉条件。 循环后的最终检查确保不会错过最后一段。 

唯一的微妙之处是正确处理重置：`cnt`必须始终重置为 1，而不是 0，因为当前元素开始一个新的潜在段。 忘记最终检查是另一个常见错误，因为最后一次运行永远不会触发中断条件。

 ## 边缘情况

 一种重要的边缘情况是阵列在连续增加期间结束。 例如，在`[1, 2, 3]`，没有“break”来触发循环内的计数。 该算法通过在迭代后执行最终检查来处理此问题。 游程长度为 3，因此正确地算作一座山。 

另一种情况是交替增加和减少，例如`[1, 3, 2, 4, 3, 5]`。 该算法在每次减少时都会重置，并且仅对达到长度 3 的段进行计数。每个段都被干净地隔离，并且不会发生部分重叠，因为`cnt`当单调性失败时立即重置。 

像高原一样`[1, 2, 2, 3]`处理正确是因为`<=`条件打破了平等的运行。 该段`[1, 2]`被丢弃，因为它的长度低于 3，并且新的运行开始于`2 -> 3`，这也太短了。
