 ## 解决方案
 ## 问题理解

 我们得到了沿着线性山路的一系列海拔。 每个索引代表一个位置，每个值代表其高度。 对于每一个查询，我们都站在一个特定的位置`p`并尝试计算在特定规则下有多少其他位置是可见的，而雾层在高度`f`根据高度关系阻挡一些能见度。 

一个位置`q`被认为是可见的`p`仅当三个条件同时成立时。 首先，海拔高度`q`必须严格低于海拔高度`p`，所以我们只看相对于查询点的“下坡”。 其次，扫描时`p`到`q`沿线，我们不得遇到任何高度至少等于`a_p`，意味着视图被第一道“墙”的高度阻挡`a_p`或更高。 第三，雾会修改实际计算的低点：如果雾高于`a_p`，所有这些可见的较低点都被计算在内，但如果雾度等于或低于`a_p`，仅高度至少为的点`f`被计算在内。 

每个查询的输出只是从给定起点满足这些可见性规则的索引数量。 

这些限制使得暴力破解变得不可行。 对于多达一百万个位置和十万个查询，任何针对每个查询扫描数组的解决方案都会太慢。 甚至一个`O(NQ)`该方法将达到大约 1011 次操作，这与两秒内的可行程度相差甚远。 这立即推动我们采用一种预处理策略，其中每个查询都可以在对数时间或更短的时间内得到回答。 

有一些失败案例出现在天真的解释中。 一个常见的错误是正确忽略阻止规则。 例如，在像这样的数组中`[1, 5, 2, 1]`，从索引开始`1`（价值`5`）， 位置`4`尽管不可见`1 < 5`，因为索引`2`有价值`5`，它会阻止其后的所有内容。 另一个微妙的问题是雾处理不当。 如果`a_p = 10`和`f = 3`, 一个有价值的点`2`即使它满足高度约束，也不被计算在内，因为雾在以下情况下将其排除在外：`f ≤ a_p`。 这些交互意味着可见性不是对值的简单范围计数，而是仅限于动态确定的段的范围计数。 

## 方法

 直接的解决方案是通过从位置左右扫描来处理每个查询`p`，每当值大于或等于时停止`a_p`遇到，并在应用雾规则时计算所有有效位置。 这在概念上是正确的，因为它准确地模拟了可见性定义。 然而，在数组严格增加或减少的最坏情况下，每次扫描几乎都会触及所有`N`元素。 和`Q`查询，这变成`O(NQ)`，这远远超出了可接受的范围。 

关键的观察是可见性由独立于查询的本地阻塞结构控制：对于每个位置`p`，从中可见的索引段是固定的。 这正是周围的最大间隔`p`至少不包含任何有价值的元素`a_p`。 这是经典的“最近大于或等于元素”结构。 一旦我们预先计算了两侧最近的阻塞边界，每个查询就减少为计算固定段中有多少值落入雾确定的值范围内。 

这将问题转化为二维范围计数问题：固定索引区间`[L, R]`和一个值区间`[low, a_p - 1]`。 其标准结构是合并排序树（排序数组的线段树），它允许对子数组中值范围内的元素进行计数`O(log^2 N)`时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的强力扫描 | O(NQ) | O(1) | O(1) | 太慢了 |
 | 预计算边界+合并排序树| O(N log N + Q log^2 N) | O(N log N + Q log^2 N) | O(N log N) | O(N log N) | 已接受 |

 ## 算法演练

 ### 1. 计算可见性边界

 对于每个索引`i`，我们计算最接近左侧和右侧的索引，其中该值至少为`a[i]`。 这是使用单调堆栈完成的。 在从左到右处理时，我们维护一个递减的堆栈，以便我们可以快速找到第一个阻塞元素。 

这一步很重要，因为这些边界之外的任何元素永远不会被`a[i]`，因此它自动与可见性无关。 

### 2.定义每个位置的可见段

 对于每个索引`i`，我们定义：

 -`L[i]`作为前一个大于或等于元素右侧的第一个索引
 -`R[i]`作为下一个大于或等于元素之前的最后一个索引

 所有可见的候选人来自`i`必须位于`[L[i], R[i]]`。 

这将几何可见性问题简化为静态子数组问题。 

### 3. 根据值构建合并排序树

 我们构造一棵线段树，其中每个节点存储其线段中所有值的排序列表。 这使我们能够使用二分搜索来计算有多少值落入给定范围。 

该结构的目的是回答以下形式的查询：“在子数组中`[L, R]`，其中有多少个值`[x, y]`”。

 ### 4. 处理每个查询

 对于查询`(p, f)`，我们首先确定可见段`[L[p], R[p]]`。 

然后我们确定有效值范围：

 - 如果`f > a[p]`，雾在观察者上方，所以所有值`< a[p]`是允许的，这意味着下限是有效的`1`- 否则，仅包含以下值`[f, a[p] - 1]`被允许

 我们将答案计算为：

 计入`[L, R]`价值观`< a[p]`减号

 计入`[L, R]`价值观`< low`### 为什么它有效

 正确性来自于分离两个独立的约束。 第一个约束是结构性的：可见性不能穿过阻塞元素，因此所有有效位置必须位于纯粹通过与`a[p]`。 第二个约束是基于值的，仅取决于雾和端点`p`，不在中间结构上。 

由于这两个约束都是对不相交维度、索引和值的单调过滤器，因此我们可以通过首先限制索引范围然后应用值范围计数来安全地使它们相交。 单调堆栈保证索引段准确且仅包含未阻塞的区域，因此在值过滤步骤之前不会排除或错误地包含有效点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_merge_sort_tree(arr):
    n = len(arr)
    size = 1
    while size < n:
        size <<= 1

    tree = [[] for _ in range(2 * size)]

    for i in range(n):
        tree[size + i] = [arr[i]]

    for i in range(size - 1, 0, -1):
        tree[i] = sorted(tree[2 * i] + tree[2 * i + 1])

    return tree, size

def query(tree, size, l, r, x):
    # count of elements <= x in [l, r]
    l += size
    r += size
    res = 0

    while l <= r:
        if l % 2 == 1:
            from bisect import bisect_right
            res += bisect_right(tree[l], x)
            l += 1
        if r % 2 == 0:
            from bisect import bisect_right
            res += bisect_right(tree[r], x)
            r -= 1
        l //= 2
        r //= 2

    return res

def build_bounds(a):
    n = len(a)
    left = [-1] * n
    right = [n] * n

    stack = []
    for i in range(n):
        while stack and a[stack[-1]] < a[i]:
            stack.pop()
        left[i] = stack[-1] if stack else -1
        stack.append(i)

    stack.clear()
    for i in range(n - 1, -1, -1):
        while stack and a[stack[-1]] < a[i]:
            stack.pop()
        right[i] = stack[-1] if stack else n
        stack.append(i)

    return left, right

def main():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    left, right = build_bounds(a)

    tree, size = build_merge_sort_tree(a)

    for _ in range(q):
        p, f = map(int, input().split())
        p -= 1

        L = left[p] + 1
        R = right[p] - 1

        ap = a[p]

        hi = ap - 1
        if hi < 0 or L > R:
            print(0)
            continue

        if f > ap:
            low = 1
        else:
            low = f

        if low > hi:
            print(0)
            continue

        def count_le(x):
            return query(tree, size, L, R, x)

        ans = count_le(hi) - count_le(low - 1)
        print(ans)

if __name__ == "__main__":
    main()
```该代码首先构建单调堆栈以确定最近的阻塞边界。 然后，它在海拔数组上构造一个合并排序树，以便每个线段树节点存储排序值以进行有效计数。 

每个查询将可见性规则转换为固定的索引区间和值区间。 最终答案是通过减去该间隔内的两个前缀计数来获得的，这精确地隔离了所需范围内的值。 

一个微妙的点是边界的处理：`left[i]`和`right[i]`存储阻塞元素的索引，因此实际有效范围不包括它们，这就是代码使用的原因`+1`和`-1`成形时发生变化`[L, R]`。

 ## 边缘情况

 一种重要的边缘情况是查询位置是稳定值或重复最大值的一部分。 对于像这样的数组`[3, 3, 3, 1]`，从索引开始`2`，最近的大于或等于边界立即包围它，将可见区域缩小到该高原部分。 该算法可以正确处理此问题，因为单调堆栈将相等视为阻塞，从而确保不会出现超出平台的等高泄漏。 

另一种情况发生在雾气低于所有可达到的值时。 在一个数组中`[8, 2, 7, 1]`和`f = 1`，仅取值于`[1, a_p - 1]`被考虑。 前缀计数的减法确保以下值`f`即使它们位于可见段内，也会被排除，这符合当观察者位于雾上方时雾阻挡过低点的可见性的条件。 

最后一个微妙的情况是可见段为空。 当两个邻居的值 ≥ 时，就会发生这种情况`a_p`毗邻于`p`。 计算出的间隔`[L, R]`变得无效，并且代码显式检查`L > R`返回零，防止在反向边界上进行错误的范围查询。
