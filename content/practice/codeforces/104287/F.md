 ## 解决方案
 ## 问题理解

 每个测试给出三个整数。 将前两个数字视为定义整数“有效”的规则：只有当一个数字可以被这两个数字整除时，该数字才有效。 第三个数字就像一个模数上限，我们仅通过余数来关心它。 

在所有有效数字中，我们可以选择任何一个我们想要的数字，甚至是非常大的数字。 对于每个选定的数字，我们计算其除以第三个数字时的余数。 任务是确定我们可以获得的最大余数。 

关键的困难在于有效数字不是任意的。 任何能被两个输入整除的数字都必须是它们的最小公倍数的倍数。 因此，搜索空间是从最小公倍数开始的无限算术级数。 

约束的值很大，但测试用例的数量适中。 最多有几千个查询，每个值最多可达 10^9。 这强烈建议每个测试用例采用对数或恒定时间的解决方案。 任何枚举倍数或模拟有效数字增长的方法都会立即失败，因为有效数字是无界的，并且模数上限也可能很大。 

一个天真的错误是假设我们只需要检查 c 以内的最小公倍数的几个倍数。 这是不安全的，因为最佳余数通常出现在模数循环结束附近，而不是开始附近。 

例如，假设最小公倍数为 6，c 为 10。有效序列为 6、12、18、24 等。 模 10 的余数为 6, 2, 8, 4, 0，重复。 最大值为 8，它不是来自任何可预测小窗口中的第一个或第二个倍数。 根据截止时间，有限的扫描可能会错过它。 

另一个微妙的问题是假设答案只是模 c 的最小公倍数。 但这会失败，因为较大的倍数可能会环绕并产生比基值更大的余数。 

## 方法

 问题中的每个有效数字都具有单个基值的倍数的形式，即两个输入的最小公倍数。 设该值为L。则所有候选者为L、2L、3L，依此类推。 

蛮力方法将生成这些值并计算它们以 c 为模的余数，在某个范围后停止。 这在概念上是正确的，但立即就崩溃了，因为我们可能需要走多远没有自然的上限。 当 c 可以是 10^9 时，即使限制到前 c 个倍数也已经太大了。 

关键的观察结果是，我们并不是试图优化原始整数，而是优化以 c 为模的残数。 一旦我们以 c 为模减少每个有效数，该结构就会变成周期性的。 序列(k·L) mod c 形成模算术中的简单循环子群。 步长是固定的，因此可达残基均匀分布在模圆周围。 

这个结构意味着可达残基的集合恰好是gcd(L,c)的倍数的集合。 由此可见，最大可达残差就是 c 之下 gcd 的最大倍数，即 c 减去 gcd。 

因此，问题完全简化为计算 L，然后进行单个 gcd 操作。

 | --- | --- | --- | --- |
 | 蛮力 | 每次测试 O(c / LCM 步骤)，最坏情况下无界 | O(1) | O(1) | 太慢了 |
 | 最佳 | O(log a + log b + log c) | O(log a + log b + log c) | O(1) | O(1) | 已接受 |

 ## 算法演练

 设 L 为 a 和 b 的最小公倍数，g 为 L 和 c 的最大公约数。

1. 计算 g1 = gcd(a, b)。 这可以识别 a 和 b 之间质因数的重叠，从而防止构建 LCM 时溢出。 最小公倍数为a*b/g1。 
2. 在乘法之前使用除法仔细计算 L：L = (a // g1) * b。 尽管 Python 在技术上可以安全地处理大整数，但这可以避免超出 32 位范围的中间溢出。 
3. 计算 g = gcd(L, c)。 这捕获了以 c 为模的可达残基的间距。 在模算术中，每个有效数都减少为 g 的倍数。 
4. 返回 c - g 作为答案。 这是严格小于 c 的最大值，位于 L 模 c 生成的残差类别中。 

步骤 3 正确的原因是乘以 L 模 c 会产生加法群模 c 的循环子群。 子组大小完全由 gcd(L, c) 决定，并且所有可达残基恰好是该 gcd 的倍数。 

## 为什么它有效

 所有有效数字都是 L 的倍数。减少模 c 将其变成固定步长 L mod c 的重复加法。 因此，可达残基的集合是由 L 在环模 c 中生成的加法子群。 该子群恰好包含 gcd(L, c) 的所有倍数。 该集合中最大的元素是绕过去 c 之前的最后一个倍数，即 c 减去 gcd(L, c)。 无法到达更大的残差，因为 L 的任何增量都只能在这个固定的格子内移动。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from math import gcd

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        a, b, c = map(int, input().split())
        
        g1 = gcd(a, b)
        l = (a // g1) * b
        g = gcd(l, c)
        
        out.append(str(c - g))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```实现直接遵循代数。 唯一微妙的部分是构建中间步骤中不溢出的 LCM，这是通过先除后乘来处理的。 

最后的减法`c - g`对应于在模块循环中选择最高可达残基。 

## 工作示例

 考虑示例输入：```
a = 2, b = 3, c = 10
```这里 L = 6。倍数表为：

 | k | d = kL | d 模 c |
 | --- | --- | --- |
 | 1 | 6 | 6 |
 | 2 | 12 | 12 2 |
 | 3 | 18 | 18 8 |
 | 4 | 24 | 4 |
 | 5 | 30 | 0 |

 最大值为 8。由于 gcd(6, 10) = 2，因此公式给出 10 - 2 = 8，与表匹配。 

现在考虑：```
a = 4, b = 2, c = 2023
```这里 L = 4。c 的 gcd 为 1，因为 2023 不能被 2 或 4 整除。 

| k | d = 4k | d 模组 2023 |
 | --- | --- | --- |
 | 1 | 4 | 4 |
 | 2 | 8 | 8 |
 | 3 | 12 | 12 12 | 12

 可达残数最终覆盖了 1 模 2023 的所有倍数，因此最大值为 2022。公式给出 2023 - 1 = 2022。

 ## 边缘情况

 当 a 和 b 相同时，最小公倍数会折叠为相同的值，并且可达集只是该数字的倍数。 对于输入 6 6 10，L 为 6，gcd(6, 10) 为 2，因此答案为 8 mod 10，匹配 10 − 2 = 8。 

当 a 和 b 互质时，L 成为它们的乘积，但结构简化了，因为 gcd(L, c) 仅取决于该乘积如何与 c 相互作用。 如果不存在共享因子，则 gcd 为 1，答案变为 c − 1，这意味着除 0 之外的所有残基都是可达的。 

当c与L共享所有质因数时，gcd等于c，答案变为0。这对应于每个有效数总是能被c整除的情况，因此不会出现正余数。
