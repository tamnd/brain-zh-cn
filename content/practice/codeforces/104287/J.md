 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 每个测试用例都有一个正整数数组。 两名玩家轮流轮流，从尼诺开始。 在一轮中，玩家选择任何单个元素并将其替换为 ⌊x/2⌋ 或 ⌊x/3⌋，但前提是结果仍然为正。 如果玩家在自己的回合中没有有效的动作，他们就输了。 问题是假设两名球员都发挥最佳状态，谁会获胜。 

关键在于游戏状态不仅仅是数组值，还包括每个值还可以执行多少个归约步骤。 除回合顺序外，每个数字均独立演化，因为每次移动仅修改一个元素。 

约束很大：最多 100000 个测试用例，总数组大小最多 100000 个。这排除了游戏树的任何每次移动模拟。 即使计算每个数字的完整游戏图也会太慢，因为如果天真地探索，最大 10^9 的单个值可能有许多简化路径。 

自然的危险是试图直接模拟动作。 例如，对于像 10^9 这样的单个值，重复除以 2 或 3 会生成一个大的状态分支树，并且组合多个这样的值会使状态空间呈指数增长。 任何明确处理每一步的方法都会失败。 

第二个微妙的问题是假设只有价值观的平等才重要。 这是错误的，因为除以 3 会产生与除以 2 不同的归约轨迹，并且它们在游戏术语中并不等效。 

## 方法

 乍一看，这是一个正常的公正组合游戏。 每个数组元素的行为就像一堆，您可以在其中以离散的步骤减小其大小。 这建议计算每个元素的 Grundy 数并对它们进行异或。 

如果我们暴力破解单个值 x，我们可以通过重复应用 x → ⌊x/2⌋ 或 x → ⌊x/3⌋ 来定义所有可达状态，同时结果保持为正。 这构建了一个有向无环状态图。 从该图中我们可以计算出格伦迪数。 这是正确的，因为每次移动都会严格减少值，因此不存在循环。 

然而，暴力生成每个 x 的所有状态的成本很高。 在最坏的情况下，每个数字都可以生成 O(log x) 深度，并且 2 个操作的分支会导致不同测试用例中的许多重复状态。 超过 10^5 值，这会变得太慢。 

关键的观察是数字的状态图是非常结构化的。 每个值最终都会映射到一小组终端状态，并且大多数路径都会快速收敛。 更重要的是，Grundy 值仅取决于我们在不同序列中可以除以 2 和 3 的次数，这减少了对一个小的可达集合中的状态进行计数，而不是探索完整的路径。 

更有效的观点是计算所有数字的 Grundy 值，直到通过除法链可达的最大可达值，但由于每个步骤都会将值至少减少 2 或 3 倍，因此所有节点上的总不同可达值足够小，可以根据测试用例动态预先计算，而无需重复。 这导致通过直接转换到 ⌊x/2⌋ 和 ⌊x/3⌋ 来记忆状态。 

一旦我们计算出每个元素的 Grundy 值，整个游戏就是独立公正游戏的总和，因此 XOR 决定了获胜者：非零 XOR 意味着第一个玩家获胜。

 ## 算法演练

 我们将每个值视为一个游戏状态，其 Grundy 数取决于其两种可能的移动。

1. 对于每个测试用例，我们独立处理每个元素，但重复使用全局记忆映射，因此不会重新计算重复的值。 这是有效的，因为游戏规则仅取决于值，而不取决于其位置。 
2. 定义函数 grundy(x)，返回值 x 的 Grundy 数。 如果 x 等于 1，则不可能进行任何移动，因此其 Grundy 数为 0。 
3. 对于 x 大于 1，我们考虑所有可达状态：x 除以 2 和 x 除以 3，但前提是结果保持为正。 这些是唯一合法的举措，因此它们完全定义了过渡结构。 
4. 递归计算 grundy(x // 2) 和 grundy(x // 3)。 将他们的结果收集到一个集合中。 
5. x 的 Grundy 值是该集合的 mex（最小排除值）。 在这个问题中，集合大小最多为 2，因此 mex 是通过按顺序检查 0、1、2 来计算的。 
6. 对数组上的所有 grundy(a_i) 进行异或。 如果结果非零，尼诺获胜； 否则 Miku 获胜。 

### 为什么它有效

 每一步都会严格减少所选元素的值，因此游戏图是非循环的并且符合标准的斯普拉格-格伦迪理论。 每个元素都是一个独立的子游戏，因为一步棋只影响一个位置。 因此，完整的游戏是独立 Grundy 值的异或。 

记忆确保每个整数值被求解一次，并且由于每次转换都会将幅度减少至少 2 或 3 倍，因此递归深度在值大小上是对数的。 这保证了DP快速收敛并且不会因重新计算而增加复杂性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

memo = {}

def grundy(x):
    if x == 1:
        return 0
    if x in memo:
        return memo[x]

    moves = set()

    nx = x // 2
    if nx > 0:
        moves.add(grundy(nx))

    ny = x // 3
    if ny > 0:
        moves.add(grundy(ny))

    g = 0
    while g in moves:
        g += 1

    memo[x] = g
    return g

t = int(input())
for _ in range(t):
    n = int(input())
    arr = list(map(int, input().split()))

    xor_sum = 0
    for v in arr:
        xor_sum ^= grundy(v)

    print("Nino" if xor_sum != 0 else "Miku")
```该解决方案是围绕记忆递归 Grundy 计算构建的。 备忘录字典确保每个值在全局范围内被评估一次。 递归直接处理两个允许的转换。 

mex 计算被简化，因为每个状态最多有两个出边，所以我们只顺序测试小整数。 

XOR 聚合实现了不相交堆的 Sprague-Grundy 定理。 

一个微妙的实现细节是全局备忘录：如果没有它，测试用例中的重复值将重新计算整个链，从而浪费时间。 另一个微妙之处是递归深度； 尽管值缩小得很快，但对抗链仍然会达到Python递归限制，因此增加了递归限制。 

## 工作示例

 我们跟踪两个示例测试用例。 

＃＃＃ 样本：`[1, 2, 5]`我们计算 Grundy 值：

 | 价值| x//2 | x//3 | 移动格伦迪套装| 格伦迪 |
 | --- | --- | --- | --- | --- |
 | 1 | - | - | ∅ | 0 |
 | 2 | 1 | 0 无效 | {0} | 1 |
 | 5 | 2 | 1 | {1, 0} | 2 |

 现在异或：0 ⊕ 1 ⊕ 2 = 3 ≠ 0，所以尼诺获胜。 

这表明，即使是从 5 开始的小分支也会产生两个不同的可达格伦迪状态，从而给出一个不平凡的 mex。 

＃＃＃ 样本：`[1, 2, 3, 4]`我们计算：

 | 价值| x//2 | x//3 | 移动格伦迪套装| 格伦迪 |
 | --- | --- | --- | --- | --- |
 | 1 | - | - | ∅ | 0 |
 | 2 | 1 | 0 无效 | {0} | 1 |
 | 3 | 1 | 1 | {0} | 1 |
 | 4 | 2 | 1 | {1, 0} | 2 |

 异或：0 ⊕ 1 ⊕ 1 ⊕ 2 = 2 ≠ 0，所以尼诺获胜。 

此迹线显示了当出现多个相同的 Grundy 值时 XOR 中的抵消效果，同时仍然留下非零结果。

 ## 边缘情况

 对于`a = [1]`，唯一的元素已经没有有效的动作，因此起始玩家立即失败。 算法返回 Grundy(1) = 0，XOR = 0，所以 Miku 获胜。 

对于像这样的大值`10^9`，递归重复应用除以 2 和 3 直到达到 1。记忆化确保像 10^9 → 5×10^8 → 2.5×10^8 这样的重叠子问题计算一次，并在整个测试套件中重复使用。 这可以防止指数爆炸。 

对于重复的相同元素，例如`[2, 2, 2, 2]`，每个贡献 Grundy(2) = 1，并且 XOR 成对取消。 该算法正确地生成 0，这意味着第二个玩家获胜，匹配相同独立桩的对称性。
