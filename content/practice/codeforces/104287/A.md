 ## 问题理解

 这个问题实际上并不在于通常的竞争性编程意义上的计算。 输入给出一个整数，称为测试用例编号，但该值不会影响答案。 无论阅读什么，任务都是输出竞赛本身引用的单个动漫或节目的名称。 

因此，真正的任务是认识到问题是要求与竞赛上下文相关的固定字符串，而不是从输入中获取任何内容。 输入存在只是因为需要 Codeforces 问题才能读取某些内容； 它实际上是噪音。 

从约束的角度来看，输入大小是微不足道的。 T 最多允许有 21 个可能的值，并且只需要处理一行。 这立即消除了任何算法推理或优化的需要。 任何读取输入并打印恒定答案的方法都可以在所有限制内顺利运行。 

在计算意义上不存在有意义的边缘情况。 唯一可能的陷阱是误解需求并尝试根据测试用例编号进行分支或推断某些隐藏的依赖关系。 例如，一个幼稚但不正确的解释可能是将 T 的不同值视为不同的输出，这是不必要的，因为该语句保证独立于输入的单个有效节目名称。 

第二个可能的错误是输出格式。 所需的输出是一个不带空格或标点符号的小写字符串。 任何超出标准打印行为的额外内容，包括空格或换行问题，都将被拒绝。 

## 方法

 暴力思维会尝试解释输入或搜索将测试用例编号映射到不同动漫名称的规则。 这不会导致任何结果，因为映射不存在。 即使尝试测试多个候选者，输出空间也明确限制为有效的节目名称，并且该问题保证仅接受正确的命名。 

关键的观察结果是输入不携带语义信息。 唯一一致的解释是比赛本身引用了一个特定的节目，任务是输出该名称。 一旦认识到这一点，解决方案就简化为打印固定的常量字符串。 

从暴力到最优的转变本质上是一个识别步骤：我们不是从输入中提取信息，而是意识到答案是在问题上下文本身中编码的。

 ## 算法演练

 1. 从输入中读取单个整数，即使它不影响结果。 这仅是正确使用输入格式所必需的。 
2. 读取后完全忽略该值，因为输出不依赖于它。 
3. 以小写形式打印表示引用的节目名称的固定字符串，不带空格。 

### 为什么它有效

 正确性来自于以下事实：问题定义了独立于输入值的单个有效输出。 由于每个有效的测试用例都有相同的预期响应，因此问题计算的函数是常量函数。 因此，无论输入如何，任何正确的解决方案都必须始终输出该常数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    _ = input().strip()
    print("bocchitherock")

if __name__ == "__main__":
    main()
```程序读取测试用例编号以满足输入要求，但随后不使用它。 打印的字符串正是指定格式所需的答案。 没有分支或计算，因为不需要。 

一个微妙的实现细节是确保输出与所需的小写格式完全匹配。 即使逻辑在其他方面是正确的，任何大写或额外的空格都会使答案无效。
