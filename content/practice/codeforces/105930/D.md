 ## 解决方案
 ## 问题理解

 我们有一个系统`n`工作节点排列成一个圆圈，索引为`0`到`n-1`。 每个任务不会转到单个节点，而是生成连续的子任务序列。 任务由两个值描述：`a`和`b`。 该任务创建`a`子任务，索引`0`通过`a-1`，以及子任务`j`被分配给节点`(b + j) mod n`。 

因此每个任务在节点环上贡献一个循环间隔。 如果我们想象写一篇长度的文章——`n`数组，每个任务添加`+1`关于指数：`b, b+1, ..., b+a-1`环绕模数`n`。 

目标是计算每个节点在处理完所有任务后有多少子任务落在该节点上。 

约束很大：在所有测试用例中，总和`n`和`q`至多是`2 × 10^5`。 这立即排除了任何单独处理每个子任务的解决方案。 单个任务可以有`a`最多`10^9`，因此显式迭代其子任务是不可能的。 

关键的困难在于，每个任务都代表一个可能会回绕的大循环间隔，我们需要有效地聚合所有这些任务。 

一些打破天真的想法的边缘情况：

 一个任务可能会多次覆盖整个循环`a >= n`。 例如，`n = 5`,`a = 12`,`b = 1`。 然后每个节点至少被访问两次，并且某些节点会获得额外的访问，具体取决于`12 mod 5`。 天真的“标记间隔一次”方法会错过重复的完整周期。 

由于包装，任务也可能分成两个段。 例如，`n = 7`,`a = 4`,`b = 5`产生节点`5, 6, 0, 1`。 将其视为单个范围`[5, 8)`如果没有模块化处理，就会产生不正确的索引。 

最后，因为`a`很大，我们必须将完整的循环与部分余数分开； 否则执行将会溢出或超时。 

## 方法

 直接模拟将通过迭代所有任务来处理每个任务`a`子任务和递增计数器。 这在概念上是正确的，因为它完全遵循定义。 然而，成本与子任务总数成正比，可以大到`q × max(a)`，远远超出任何可行的限制，当`a`达到`10^9`。 

该操作的结构提出了经典的循环差分阵列思想。 每个任务都会在整个环上多次添加恒定的贡献，再加上最后的部分片段。 如果我们分解`a`作为`a = k·n + r`，那么每个节点都准确地接收到`k`来自整个周期的贡献。 这部分是统一的，可以全局添加而无需触及各个节点。 

剩下的是长度的单个线性区间`r`开始于`b`圆形阵列上。 这是循环数组上的标准范围更新问题。 我们可以使用差异数组来处理它：将每个间隔转换为两个点更新，然后在最后取前缀和。 

这种分离之所以有效，是因为圆形结构是规则的。 每个完整的旋转都是相同的，因此它在各处都会产生恒定的偏移。 只有其余部分取决于位置。

 | --- | --- | --- | --- |
 | 蛮力 | O(Σa) | O(n) | 太慢了|
 | 最优（循环分解+差异数组）| O(n + q) | O(n) | 已接受 |

 ## 算法演练

 ### 1.初始化一个数组`diff`尺寸的`n + 1`和一个变量`base = 0`差异数组将仅累积部分段。 这`base`变量存储所有任务的完整周期的贡献。 

### 2. 对于每项任务`(a, b)`, 计算`k = a // n`和`r = a % n`价值`k`表示围绕圆发生了多少次完整的循环。 每整轮加起来正好`1`到每个节点，所以我们延迟应用它。 

我们积累`base += k`对于每项任务。 

### 3.如果`r == 0`，继续下一个任务

 当没有剩余时，任务仅由完整的循环组成，因此它的贡献是均匀的并且不需要范围更新。 

### 4. 否则，应用长度的循环范围更新`r`开始于`b`我们根据间隔是否回绕将其分为两种情况。 

如果`b + r - 1 < n`，该段是连续的，所以我们这样做：`diff[b] += 1`,`diff[b + r] -= 1`。 

如果它环绕，则说它结束于`t = (b + r - 1) % n`，然后我们更新：`diff[b] += 1`,`diff[n] -= 1`,`diff[0] += 1`,`diff[t + 1] -= 1`。 

这正确地表示了增量`[b, n-1]`和`[0, t]`。 

### 5. 转换`diff`使用前缀和进入最终数组

 我们计算运行总和`diff`，并且对于每个位置`i`，最终的答案是`base + prefix_sum[i]`。 

### 为什么它有效

 每个任务分解为`k`完整旋转和一个部分圆弧。 完整旋转对每个节点的贡献相同，因此将它们存储在单个标量中`base`保留正确性。 差异数组精确捕获部分弧，前缀求和重建每个节点的总重叠。 由于每个贡献要么是全局统一的，要么是单个区间，因此任务之间的交互不会破坏这种分解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    diff = [0] * (n + 1)
    base = 0

    for _ in range(q):
        a, b = map(int, input().split())
        k = a // n
        r = a % n

        base += k

        if r == 0:
            continue

        l = b
        rr = (b + r - 1)

        if rr < n:
            diff[l] += 1
            diff[rr + 1] -= 1
        else:
            rr %= n
            diff[l] += 1
            diff[n] -= 1
            diff[0] += 1
            diff[rr + 1] -= 1

    ans = [0] * n
    cur = 0
    for i in range(n):
        cur += diff[i]
        ans[i] = cur + base

    print(*ans)

t = int(input())
for _ in range(t):
    solve()
```解决方案首先将全球贡献与本地贡献分开。 这`base`变量累积每个任务的完整周期。 这可以避免接触数组以进行概念上同等影响所有节点的操作。 

这`diff`数组仅存储部分弧的调整。 每次更新最多转换为两个或四个点操作，具体取决于是否发生回绕。 然后，前缀和重建将这些转换为最终的每节点计数。 

一个微妙的点是正确处理环绕。 该实现不是尝试连续模拟模运算，而是将循环间隔分成最多两个线性段，这使所有操作保持在标准差分数组逻辑内。

 ## 边缘情况

 一个关键的边缘情况是当`a`是的倍数`n`。 在那种情况下，`r = 0`，所以整个贡献被吸收到`base`。 该算法跳过任何差异更新，每个节点都准确接收`a / n`增量。 这与定义相匹配，因为每个完整旋转每个周期恰好覆盖每个节点一次。 

另一种边缘情况是当间隔环绕数组末尾时。 为了`n = 5`,`a = 3`,`b = 4`，受影响的节点是`4, 0, 1`。 该算法将其分为`[4,4]`和`[0,1]`使用两个差异更新，并且前缀和准确地重建这三个位置。 

最后非常大`a`值测试整数分解是否正确应用。 由于所有繁重的工作都减少到`a // n`和`a % n`，该算法避免了迭代`a`完全，所以甚至值高达`10^9`安全处理，不会降低性能。
