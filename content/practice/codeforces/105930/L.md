 ## 解决方案
 ## 问题理解

 每个输入测试用例都给出以固定格式编写的两个恒星分类：大写字母后跟数字。 该字母代表粗略的温度等级，从最热到最冷排列为 O、B、A、F、G、K、M。在每个等级中，从 0 到 9 的数字细化温度，其中 0 较热，9 较冷。 

因此，每个分类实际上都是一维温标上的一个点，具有 70 个可能的离散值。 任务是比较两个这样的点，并确定第一颗恒星是否更热、更冷，或者与第二颗恒星的温度完全相同。 

限制很小：最多 1000 次比较，每次比较都涉及恒定时间处理。 这立即表明，任何解析每一对并在 O(1) 内进行比较的解决方案就足够了，而任何涉及排序或复杂模拟的解决方案都是不必要的开销。 

一个微妙的失败案例来自于按字典顺序比较字符串。 例如，将“A9”和“B0”作为字符串进行比较在这里会意外地起作用，因为字母顺序与 ASCII 顺序匹配，但依赖于此很脆弱，如果编码或表示形式发生更改，则可能会中断。 另一个潜在的错误是忽略了数字比较的含义是相反的：数字较小意味着更热，而不是更冷。 

边缘情况主要与边界字母和数字有关。 例如，将 O0 与 O0 进行比较应该得到相同的结果。 将 M9 与 O0 进行比较，首先应该得出较冷的结果，因为 M9 可能是最冷的，而 O0 是最热的。 

## 方法

 解释该问题的一种强力方法是将每个分类显式映射到 0 到 69 范围内的数字温度值。我们将 O0 指定为 0，O1 指定为 1，...，O9 指定为 9，然后 B0 指定为 10，依此类推，直到 M9 指定为 69。一旦两个输入都被转换，比较就简化为整数比较。 

这是有效的，因为分类系统首先按字母类别严格排序，然后按类别内的数字排序。 暴力映射已经是恒定的大小，因此很有效，但它有点间接。 

我们可以通过观察字母的自定义字母表和每个字母内的数字的相反顺序来进一步简化。 我们可以计算字母的索引并将其与数字组合起来，而不是构建完整的映射表。 

令字母等级 O、B、A、F、G、K、M 对应于 0 到 6。那么一颗星表示为`rank(letter) * 10 + digit`。 这直接将总排序编码为单个整数，从而保留了正确性。 

暴力方法使用每个字母的字典查找，而最佳方法用直接算术编码代替它。 每个测试用例的复杂度都是 O(1)，但后者更干净并且避免了额外的数据结构。

 ## 算法演练

 我们想要每个分类的直接数字表示，以便比较变成简单的整数比较。 

1. 读取每个测试用例的两个分类字符串。 每个字符串的长度正好为 2，因此解析时间为常数。 
2. 根据字母在温度序列 O、B、A、F、G、K、M 中的位置，将字母转换为 0 到 6 之间的等级。此排序是固定的，定义了粗略的温度级别。 
3. 将数字字符转换为 0 到 9 之间的整数。该数字细化了其字母类别内的温度。 
4. 将单个整数值计算为`rank * 10 + digit`。 这是可行的，因为每个字母类恰好涵盖 10 个值，并且每个类中的数字顺序是一致的。 
5. 对两个星重复此操作，产生两个整数。 
6. 比较两个整数。 如果第一个较小，则它对应于较热的恒星，因为 O0 是最小值。 如果更大，则更凉爽。 如果相等，则两个分类相同。 

这种转换有效的关键原因是原始排序已经被构造为按字典顺序排序的产品：主键是字母类别，辅助键是逆热顺序中的数字。 

### 为什么它有效

 该映射保留了顺序，因为字母类别在温度上是严格单调的，并且每个类别恰好包含 10 个均匀排序的细分。 类之间不存在重叠，因为乘以 10 将它们分成不相交的区间。 在一个类中，数字比较与温度方向一致，因此组合整数完全编码原始排序而不会产生歧义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

order = {
    'O': 0,
    'B': 1,
    'A': 2,
    'F': 3,
    'G': 4,
    'K': 5,
    'M': 6
}

def encode(s):
    return order[s[0]] * 10 + (ord(s[1]) - ord('0'))

t = int(input())
out = []

for _ in range(t):
    a, b = input().split()
    va = encode(a)
    vb = encode(b)

    if va < vb:
        out.append("hotter")
    elif va > vb:
        out.append("cooler")
    else:
        out.append("same")

print("\n".join(out))
```该解决方案首先定义光谱类别的固定顺序。 这避免了比较期间重复的条件逻辑。 使用编码函数将每个分类字符串转换为紧凑整数，从而分别隔离字母贡献和数字贡献。 

一个常见的错误是直接比较字符串。 虽然它可能会传递一些数据集，但它依赖于 ASCII 排序，并且没有显式编码科学排序。 另一个微妙的问题是忘记了较小的编码值对应于较热的恒星，因此比较方向必须仔细与映射的含义保持一致。

 ## 边缘情况

 一种边缘情况是比较相同的恒星，例如`M9 M9`。 编码给出的结果都是 6*10+9=69，并且算法正确地输出相同的结果，因为完全保留了相等性。 

另一个边缘情况是类之间的边界，例如`B0 A9`。 编码产生 B0 = 1_10+0=10 和 A9 = 2_10+9=29，因此 B0 被正确地识别为更热，尽管在其他类别中具有较小的数字范围优势。 

最后一种情况是类内逆转，例如`F8 F1`。 编码分别给出 38 和 31，因此 38 > 31 并且第一颗星的输出更冷，这与数字越高意味着同一类中更冷的事实相匹配。
