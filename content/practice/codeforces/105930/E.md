 ## 解决方案
 ## 问题理解

 我们得到一个正整数列表，并且允许我们精确地执行$k$运营。 每个操作都会选择一个位置并将该元素增加 1。应用所有增量后，我们查看整个数组的最大公约数，并希望最大化该值。 

更具体地说，我们从一个数组开始，预算为$k$单位增量。 我们可以在元素之间任意分配这些增量，但只能以单位步骤进行。 在花费所有增量之后，我们希望结果数字共享一个大的公约数。 

关键的困难在于我们不允许减少价值，只能增加价值，而且我们必须精确地花费$k$增量，最多不是$k$。 

约束条件意味着$n$所有测试用例的最大可达$10^6$，以及值$a_i$也共同受到$10^6$。 这立即排除了任何在每个测试用例的值范围内重新计算二次值的方法。 依赖于检查所有对或模拟操作的解决方案是不可能的。 总和为$k$非常大，最多$10^{12}$，这也意味着我们无法直接模拟操作。 

一个微妙的边缘情况来自“完全$k$” 要求。如果候选目标 gcd 使用少于$k$增量，我们不能立即接受它，除非我们仍然可以在不破坏 gcd 的情况下分配剩余的增量。 

例如，假设我们想要 gcd$g = 2$，我们已经可以仅使用 3 个增量将数组调整为 2 的倍数，但是$k = 5$。 如果我们任意添加剩余的 2 个增量，除非我们仔细构建它们，否则我们可能会破坏整除性。 

另一种边缘情况是当所有元素都已经是一个大数的倍数时。 那么答案不仅仅是初始的 gcd，因为我们可以使用剩余的操作进一步增加它。 

## 方法

 一个蛮力的想法是猜测最终的 gcd$g$，构造一个有效的最终数组，并检查是否可以达到可被整除的值$g$最多使用$k$增量。 对于固定的$g$, 每个元素$a_i$必须增加到下一个倍数$g$。 每个元素的成本是到该倍数的距离，对所有元素求和给出了使所有元素都能整除的最小成本$g$。 

这种粗暴的方法会迭代所有可能的方法$g$大约达到$\max(a_i) + k$，并且对于每个$g$从头开始重新计算成本$O(n)$。 这导致$O(n \cdot \max A)$，当$\max A = 10^6$。 

关键的观察是一旦我们确定了候选 gcd$g$，每个数字独立地贡献一个确定性成本：它必须向上舍入到下一个倍数$g$。 这将问题转化为计算有多少值落入每个残差类模$g$，并对模块化调整求和。 

剩下的微妙之处是处理额外的$k - \text{cost}$运营。 由于准确添加$g$任何元素都保持整除性$g$，剩余操作仅在大小块中有效$g$。 这导致了剩余部分必须能被整除的条件$g$。 

然后我们扫描所有可能的$g$，计算可行性，并取最大有效值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对每个进行强力重新计算$g$|$O(n \cdot \max A)$|$O(\max A)$| 太慢了|
 | 优化的残留计数$g$|$O(\max A \log \max A)$|$O(\max A)$| 已接受 |

 ## 算法演练

 对于每个测试用例，我们针对输入中的所有值构建一个频率数组。 这使我们能够有效地回答任何算术级数中有多少个元素。 

然后我们尝试每个候选 gcd$g$从 1 到最大可能值。 

1.对于固定的$g$，计算使每个元素可被整除所需的最小增量数$g$。 对于每个元素$a_i$，所需增加量为$(g - a_i \bmod g) \bmod g$。 我们使用频率计数对所有元素求和。 
2. 如果总成本超过$k$， 然后$g$这是不可能的，我们跳过它。 
3.如果成本最多$k$，我们计算剩余的$k - \text{cost}$。 这个剩余部分必须可以在不破坏整除性的情况下使用。 唯一安全的操作是添加$g$对于任何元素，因此剩余部分必须能被整除$g$。 
4. 如果两个条件都成立，我们标记$g$尽可能可行。 
5.我们采取最大可行的$g$。 

这样做的原因是任何带有 gcd 的有效最终数组$g$所有元素必须与 0 模一致$g$。 由于我们只能增加值，因此每个元素的最优策略是独立的：将其推到最接近的倍数$g$。 任何偏差只会增加成本，而不会提高可行性。 达到有效的配置后，剩余的操作不能随意使用，它们必须保持可分性，这迫使它们分成大小的块$g$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        mx = max(a)
        freq = [0] * (mx + 1)
        for v in a:
            freq[v] += 1
        
        # prefix not needed, we use frequency directly
        
        ans = 1
        
        for g in range(1, mx + 1):
            cost = 0
            
            # compute cost to make all numbers divisible by g
            for r in range(g):
                # sum over v = r + t*g
                add = 0
                v = r
                while v <= mx:
                    add += freq[v]
                    v += g
                
                if add == 0:
                    continue
                
                # all numbers in this residue contribute (g - r) mod g
                if r == 0:
                    continue
                cost += add * (g - r)
                if cost > k:
                    break
            
            if cost > k:
                continue
            
            if (k - cost) % g == 0:
                ans = g
        
        print(ans)

if __name__ == "__main__":
    solve()
```代码首先将输入压缩到频率数组中，这样我们就不会重复迭代元素。 对于每个候选gcd$g$，它处理残差类模$g$。 对于每个残基$r$，它遍历值$r, r+g, r+2g, \dots$并计算有多少个数字落在那里。 

每个这样的数字都准确地贡献$(g - r)$递增以达到下一个倍数$g$，因为该残数中的所有值共享相同的余数。 

最终的可行性检查强制执行预算约束和剩余操作的可分性，这确保我们可以安全地分配剩余的增量。

 ## 边缘情况

 一个关键的边缘情况是当数组已经可以被候选者完全整除时$g$。 在这种情况下，成本为零，正确性完全取决于是否$k$是的倍数$g$。 该算法自然地处理这个问题，因为剩余部分仍然必须保持整除性，迫使$k \bmod g = 0$。 

另一个边缘情况是当$g = 1$。 每个数组无需任何操作即可被 1 整除，因此成本始终为零，并且答案始终至少为 1。该算法正确地保持$g = 1$作为后备。 

当出现第三种边缘情况时$k$足够大以超过任何直接舍入成本。 该算法仍然通过取模条件来限制可行性，确保多余的操作不会默默地使 gcd 失效。
