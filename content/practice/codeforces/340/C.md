 ## 解决方案
 ## 问题理解

 我们有几个位于直线上的目的地$a_1,a_2,\dots,a_n$，所有这些都严格积极且独特。 路线只是这些目的地的排列。 游客从位置 0 开始，按照所选顺序访问目的地，并在访问最后一个目的地后停止。 

对于路线$p_1,p_2,\dots,p_n$，行驶的距离为$$a_{p_1} + \sum_{i=2}^{n} |a_{p_i}-a_{p_{i-1}}|.$$任务不是找到最佳路线。 我们必须计算所有的平均距离$n!$可能的路线和输出平均为不可约分数。 

约束条件$n \le 10^5$立即排除任何涉及排列枚举的事情。 甚至$n=15$已经会让$n!$大得令人绝望。 我们需要一个公式来汇总所有路线上每个目的地对的贡献。 

职位可以大到$10^7$，最终的分子可以是$n^2 \cdot 10^7$，因此需要 64 位算术。 Python 整数会自动处理这个问题。 

出现微妙的边缘情况时$n=2$。 

输入：```
2
1 10
```两条路线各有长度$10$和$19$。 他们的平均值是$29/2$。 

一个粗心的解决方案只计算对转换并忘记从位置 0 开始的初始移动会产生$9$，这是完全错误的。 

另一个容易犯的错误是错误地计算了有多少个排列包含相邻的特定对。 

输入：```
3
2 3 5
```这对$(2,5)$恰好相邻出现$2\cdot (n-1)! = 4$排列，并非全部$6$。 如果这个组合因素错误，就会导致平均值不正确。 

第三个陷阱是忘记减少最后的分数。 

输入：```
2
1 3
```平均距离是$(3+5)/2 = 4$，所以正确的输出是：```
4 1
```印刷`8 2`将无法满足要求。 

## 方法

 蛮力的想法很简单。 生成目的地的每个排列，计算其路线长度，将所有路线长度相加，然后除以$n!$。 

这是有效的，因为答案的定义实际上是所有排列的平均值。 不幸的是，有$n!$路线。 为了$n=10^5$，甚至写下数字$n!$是不可能的，更不用说迭代所有排列了。 

关键的观察是，所有排列的平均值通常可以通过计算每个组件出现的频率来计算。 

路线长度由两种术语组成。 

第一项是从 0 到第一个访问的目的地的距离。 

其余项是排列中连续目的地之间的距离。 

我们不是对整个路线进行推理，而是计算每个目的地和每个目的地对对所有排列的贡献。 

对于起始位置，每个目的地首先准确地出现$(n-1)!$排列。 因此启动的总贡献是$$(n-1)! \sum a_i.$$对于连续转换，请考虑两个目的地$x$和$y$。 有多少种排列使它们彼此相邻？ 

对待$(x,y)$作为一个块。 该块可以通过两种方式排序，并与剩余的一起排序$n-2$我们有的目的地$n-1$要排列的对象。 

因此计数是$$2\cdot (n-1)!.$$每个这样的排列都有助于$|x-y|$。 

因此所有邻接项的总贡献为$$2(n-1)! \sum_{i<j} |a_i-a_j|.$$结合两部分给出$$\text{Total over all permutations} = (n-1)! \left( \sum a_i + 2\sum_{i<j}|a_i-a_j| \right).$$除以$n!$取消阶乘：$$\text{Average} = \frac{ \sum a_i + 2\sum_{i<j}|a_i-a_j| }{n}.$$现在整个问题归结为计算$$\sum_{i<j}|a_i-a_j|.$$对位置进行排序后，所有差异都变为非负数：$$\sum_{i<j}(a_j-a_i).$$使用前缀和排序后，可以在线性时间内计算出这个经典量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n!\cdot n)$|$O(n)$| 太慢了 |
 | 最佳 |$O(n\log n)$|$O(1)$额外 | 已接受 |

 ## 算法演练

 1. 读取位置并排序。 

排序允许我们用普通差异替换绝对值，因为对于$i<j$，我们有$a_j \ge a_i$。 
2. 计算所有位置的总和。 

这就是组合简化后起始动作的贡献。 
3. 计算$\sum_{i<j}(a_j-a_i)$。 

维护一个运行的前缀和。 

加工时$a_i$，所有早期值都有贡献$$a_i \cdot i - \text{prefix}.$$这等于$$\sum_{j<i}(a_i-a_j).$$4.让$D$是上一步得到的两两差值和。 
5. 计算$$\text{numerator} = \sum a_i + 2D.$$平均值是分子除以$n$。 
6. 通过将分子和分母除以它们的最大公约数来减少分数。 
7. 输出约简后的分子和分母。 

### 为什么它有效

 每条路线长度都是一个起始贡献和多个邻接贡献的总和。 在所有排列中，每个目的地首先准确地出现$(n-1)!$次，给出术语$\sum a_i$。 同样，每对无序的目的地都完全相邻$2(n-1)!$次，给出术语$2\sum_{i<j}|a_i-a_j|$。 

这些计数是精确的，并且恰好涵盖了每个排列中的每个距离贡献一次。 除以排列总数后$n!$，平均路径长度变为$$\frac{\sum a_i + 2\sum_{i<j}|a_i-a_j|}{n}.$$排序前缀和计算精确地计算成对差值和，因此该算法无需近似即可计算所需的平均值。 

## Python 解决方案```python
import sys
from math import gcd

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    total_positions = sum(a)

    prefix = 0
    pair_sum = 0

    for i, x in enumerate(a):
        pair_sum += x * i - prefix
        prefix += x

    numerator = total_positions + 2 * pair_sum
    denominator = n

    g = gcd(numerator, denominator)

    print(numerator // g, denominator // g)

solve()
```第一步对坐标进行排序。 一旦排序，每对贡献就变成$a_j-a_i$而不是$|a_j-a_i|$，这使得聚合成为可能。 

变量`pair_sum`商店$$\sum_{i<j}(a_j-a_i).$$处理当前值时`x`在索引处`i`，正好有`i`之前的元素。 他们的总贡献是$$(x-a_0)+(x-a_1)+\cdots+(x-a_{i-1}),$$这简化为`x * i - prefix`。 

最终公式直接来自组合计数参数：$$\text{average} = \frac{\sum a_i + 2\,\text{pair\_sum}}{n}.$$不计算阶乘。 这是使问题变得可行的关键简化。 

即使中间值变得非常大，Python 的任意精度整数也可以避免溢出问题。

## 测试用例```python
import sys
import io
from math import gcd

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))

    a.sort()

    prefix = 0
    pair_sum = 0

    for i, x in enumerate(a):
        pair_sum += x * i - prefix
        prefix += x

    numerator = sum(a) + 2 * pair_sum
    denominator = n

    g = gcd(numerator, denominator)
    return f"{numerator // g} {denominator // g}"

# provided sample
assert run("3\n2 3 5\n") == "22 3", "sample 1"

# minimum n
assert run("2\n1 2\n") == "5 2", "minimum size"

# reducible fraction becoming integer
assert run("2\n1 3\n") == "4 1", "fraction reduction"

# unsorted input
assert run("3\n5 2 3\n") == "22 3", "sorting correctness"

# larger gaps
assert run("3\n1 10 20\n") == "79 3", "pairwise contribution"

 ## 边缘情况

 考虑：```
2
1 10
```排序后两两差值和为$9$。 公式给出$$\frac{1+10+2\cdot 9}{2} = \frac{29}{2}.$$该算法正确地包括了第一个访问的目的地的贡献。 省略该术语将错误地产生$9$。 

考虑：```
3
5 2 3
```排序将数组转换为$[2,3,5]$。 两两求和变为$6$，生产$22/3$。 这证实了答案仅取决于位置，而不取决于它们在输入中的顺序。 

考虑：```
2
1 3
```公式给出$$\frac{1+3+2(2)}{2} = \frac{8}{2} = 4.$$gcd 步骤将分数减少为`4 1`，满足输出不可约的要求。 

考虑：```
4
1 2 3 10000000
```两两差值和非常大，但所有计算仍然是整数运算。 Python 安全地处理结果值，并且组合公式避免任何阶乘大小的数字。
