 ## 解决方案
 ## 问题理解

 我们从两个值开始，`x = 0`和`a = 1`，并且想要制作`x`等于给定目标`n`使用尽可能少的操作。 第一个操作添加当前`a`到`x`。 第二次操作首先替换`a`按目前的`x`，然后添加这个新的`a`到`x`，所以它的作用就是变换`(a, x)`进入`(x, 2x)`。 任务是输出每个测试用例所需的最少操作数。 原问题最多有 50 个目标，每个目标最多`10^9`。 

界限`n <= 10^9`排除任何与`n`每个测试用例。 即使是需要每个单元进行一次操作的简单模拟，对于单个目标也需要多达十亿次操作，这远远超出了一秒的限制。 我们需要利用运算的算术结构，而不是显式地构造序列。 测试用例数量只有50个，所以`O(sqrt(n))`每个案例的因式分解很容易足够快。 

有两种边缘情况值得关注。 为了`n = 1`，答案是`1`，因为第一个加法改变了`x`从`0`到`1`。 基于素因数的公式必须单独处理这个问题，因为`1`没有素因数。 为了`n = 2`，答案是`2`: 首先获取`x = 1`，然后使用第二个操作将其加倍。 一个粗心的实现，仅返回素因子贡献将返回`1`，所以最终公式中额外的常数是必不可少的。 

## 方法

 直接的暴力方法可以处理每个状态`(a, x)`作为一个节点并尝试其中的两个操作。 由于每个有用的操作都会增加`x`，广度优先搜索最终会找到到达的最短路径`n`。 问题在于搜索空间的大小。 即使我们最多只考虑长度的操作序列`n`, 可以有`2^n`不同的操作字符串。 为了`n = 10^9`，这是完全不可行的。 重复使用第一个操作的更简单的暴力策略可能需要精确`n`行动，这也已经太大了。 

有用的观察来自以下事实：`a`总是分裂`x`。 最初`a = 1`划分`x = 0`，并添加`a`保留可分性。 第二次操作变化`(a, x)`到`(x, 2x)`，因此整除性再次被保留。 

假设当前状态是`x = ka`。 如果我们执行第一个操作一次，比率就会从`k`到`k + 1`。 如果我们最终使用第二个操作，则当前值`x`被复制到`a`然后翻倍。 这意味着整组操作可以解释为将累加值乘以整数因子。 

因式分解的观点是关键。 将目标写为质因数的乘积

 [
 n = p_1p_2\cdots p_k。 
]

 对于每个中间素因子`p`，我们可以用`p - 1`运营。 最后一个素因数只需要`p - 2`最后倍增阶段后添加。 开始于`1`进入第一个倍增阶段需要两次操作。 得到的总和是

 [
 2 + \sum_{i=1}^{k-1}(p_i-1) + (p_k-2)
 = 1 + \sum_{i=1}^{k}(p_i-1)。 
]

 同样的表达方式是最优的，而不仅仅是可实现的。 对于每个整数`m >= 2`, 定义

 [
 S(m)=\sum (p-1),
 ]

 其中总和涵盖了所有素因数`m`，具有多重性。 我们有`S(m) <= m - 1`。 每个中间乘法因子`m`至少花费`m - 1`，而第一个因素的成本比该因素多 1 个，而最后一个因素的成本则少 1 个。 结合所有因素的这些不平等给出了下限`S(n) + 1`。 上面的构造正好达到了这个界限。 

所以整个问题归结为素因数分解。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 最坏情况下的 O(2^n) | O(2^n) | O(2^n) | 太慢了 |
 | 线性模拟 | O(n) | O(1) | O(1) | 太慢了 |
 | 质因数分解 | O(sqrt(n)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.如果`n = 1`， 返回`1`。 通过一次添加初始值即可达到目标`a = 1`。 
2. 设置`answer = 1`。 这是公式中的常数项`1 + S(n)`。 
3.因素`n`通过尝试除数`2`向上同时`p * p <= n`。 每当`p`划分`n`， 添加`p - 1`到答案并除以`n`经过`p`。 我们重复除法，因为同一个素数可能出现多次。 
4. 循环结束后，如果剩余值`n`大于`1`，它是素数。 添加`n - 1`到答案。 
5. 打印结果答案。 

### 为什么它有效

 考虑无用的初始操作后的任何有效序列`x = 0`已被删除。 因为`a`总是分裂`x`，将当前状态写为`x = ka`。 首次运营连续增加`k`一个。 当使用第二个操作时，当前值`x`成为新的`a`， 和`x`变为旧值的两倍。 因此，两次第二操作之间的序列的每个部分都会为最终值贡献一个乘法因子。 

对于任意整数`m >= 2`，其素因子贡献满足`S(m) <= m - 1`。 中间因素`m`至少花费`m - 1`，所以至少花费`S(m)`。 初始因子成本至少为`S(m) + 2`，最终的因子成本至少`S(m) - 1`。 将这些界限加到所有因素上至少给出`S(n) + 1`运营。 

反之，取素因数分解`n`。 开始于`x = 1`。 使用第二次操作进入倍增状态。 对于除最后一个之外的每个素因数，使用`p - 2`加法后进行第二次操作，这引入了一个因子`p`成本为`p - 1`。 对于最终的素因数，使用`p - 2`添加而无需再次加倍。 总数正好是`1 + S(n)`。 因此，该公式既是可实现的，也是最小的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n):
    if n == 1:
        return 1

    answer = 1
    p = 2

    while p * p <= n:
        while n % p == 0:
            answer += p - 1
            n //= p
        p += 1

    if n > 1:
        answer += n - 1

    return answer

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        out.append(str(solve_case(n)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```这`solve_case`函数处理特殊值`1`第一的。 对于所有其他目标，`answer`开始于`1`，代表证明公式中的常数项。 

因式分解循环尝试每个可能的除数，直到当前剩余值的平方根。 当找到除数时，内部循环会删除该质数的所有出现并添加`p - 1`每次出现一次。 例如，`12 = 2 * 2 * 3`贡献`1 + 1 + 2`。 

循环结束后，剩余值大于`1`因子最多不能为平方根，因此它本身必须是素数。 添加`n - 1`处理最后的素因数。 

使用`p * p <= n`而不是`p <= sqrt(n)`避免了浮点运算，并且随着因子的去除而变得更加严格。 Python整数在这里没有溢出问题，最大的试除数只有大约`31623`。 

## 工作示例

 对于样本目标`n = 3`，最优序列仅使用第一个操作。 开始于`(a, x) = (1, 0)`，每个操作添加`1`。 

| 步骤| 运营|`a`|`x`|
 | ---| ---| ---| ---|
 | 0 | 开始| 1 | 0 |
 | 1 | 添加`a`| 1 | 1 |
 | 2 | 添加`a`| 1 | 2 |
 | 3 | 添加`a`| 1 | 3 |

 质因数分解很简单`3`，所以公式给出`1 + (3 - 1) = 3`。 跟踪恰好通过三个操作到达目标。 

对于样本目标`n = 4`，其因式分解为`2 * 2`，所以公式给出

 [
 1+(2-1)+(2-1)=3。 
]

 该序列使用第二个操作来利用加倍行为。 

| 步骤| 运营|`a`|`x`|
 | ---| ---| ---| ---|
 | 0 | 开始| 1 | 0 |
 | 1 | 添加`a`| 1 | 1 |
 | 2 | 添加`a`| 1 | 2 |
 | 3 | 复制`x`到`a`，然后添加 | 2 | 4 |

 这三个操作与示例输出匹配。 第二步后的状态有`a = 1`和`x = 2`，所以第二次操作加倍`x`到`4`。

 ## 边缘情况

 对于`n = 1`，输入是`1`并且算法立即返回`1`。 由于不存在质因数，所以不尝试质因数分解。 直接序列很简单`(1,0) -> (1,1)`，所以特殊情况是精确的而不是实现方便。 

为了`n = 2`，因式分解为`2`。 公式给出`1 + (2 - 1) = 2`。 顺序是`(1,0) -> (1,1) -> (1,2)`。 忘记常数的解决方案`1`会错误地声称一次操作就足够了。 

为了`n = 4`，重复因式分解为`2 * 2`。 该算法添加`1`两次初始答案，产生`3`。 对应的操作是`x = 1`， 然后`x = 2`，那么第二个操作改变`(a,x) = (1,2)`进入`(2,4)`。 这可以捕获涉及重复素因数的错误。 

为了`n = 15`，主要因素是`3`和`5`, 给予`1 + 2 + 4 = 7`。 一种最佳序列是`x = 1`， 然后`x = 2`， 然后`x = 3`，那么第二个操作给出`x = 6`，然后使用三个添加`a = 3`，生产`9`,`12`，最后`15`。 七个运算与公式相匹配。 

为了`n = 10^9`，因式分解为`2^9 * 5^9`。 贡献是`9(2-1) + 9(5-1) = 9 + 36 = 45`，所以答案是`46`。 该实现不会迭代到`10^9`; 它消除了小因子并立即完成，这正是分解方法适合约束的原因。
