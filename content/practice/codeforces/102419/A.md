 ## 解决方案
 ## 问题理解

 我们有两个字符串`a`和`b`相同长度的。 我们必须选择两个不同的位置并同时交换两个字符串中的这些位置。 目标是使结果`a`按字典顺序大于结果`b`。 

关键的细节是掉期会移动整个货币对`(a[i], b[i])`。 我们不会独立地从两个字符串中选择字符。 如果位置`i`被移动到位置`j`，它的两个角色一起移动。 

字典顺序比较由两个字符串不同的第一个位置决定。 在这样的位置上，`a`恰好在什么时候获胜`a[i] > b[i]`。 因此，对于每个位置，只有两个角色之间的关系很重要：`a[i] > b[i]`意味着这个立场有利于`a`。`a[i] = b[i]`意味着这个立场是中立的。`a[i] < b[i]`意味着这个位置不利于`a`。 

长度可以达到`10^5`，因此检查每对位置然后比较结果字符串的算法过于昂贵。 有大约`n^2 / 2`可能的交换，并且比较两个字符串可能需要`O(n)`, 给予`O(n^3)`角色在最坏的情况下工作。 和`n = 10^5`，我们需要一个线性或近线性的解。 

有几个小案例可能会愚弄幼稚的策略。 例如，```
2
ba
ab
```这里原来的第一个位置有`b > a`，但唯一可能的交换是将不利的第二对移动到前面。 结果是`ab`相对`ba`，所以答案是`NO`。 只是找到一个位置`a[i] > b[i]`当该位置已经是第一个并且`n = 2`。 

另一种情况是```
3
abc
abc
```每个头寸都是中立的，因此任何掉期都不能创建这样的头寸：`a`具有较大的特征。 答案是`NO`。 假设任何交换都可以改变比较的解决方案将错误地接受这种情况。 

在另一个极端，```
3
zzz
aaa
```已经有`a[0] > b[0]`。 我们被要求交换，但我们可以交换位置`2`和`3`，保持第一个位置不变。 答案是`YES`。 

## 方法

 直接的暴力方法是尝试每一对`(x, y)`，在两个字符串的副本中执行交换，并按字典顺序比较结果字符串。 有`n(n-1)/2`对，即`O(n^2)`，并且每次比较都可以检查`O(n)`人物。 最坏的情况是这样`O(n^3)`。 为了`n = 100000`，这大约是`10^15`人物级操作，远远超出时间限制。 

有用的观察是我们实际上并不关心每个位置的确切字符。 对于字典序比较，只需根据比较的情况将一个立场分为有利、中立或不利。`a[i]`和`b[i]`。 

假设我们找到一个位置`p`在哪里`a[p] > b[p]`。 如果`p`不是第一个位置，交换位置`0`和`p`立即解决问题。 交换后位置`0`包含来自的旧对`p`，所以新的字符串满足`a[0] > b[0]`。 因此，无论稍后发生什么，字符串都会正确排序。 

如果有利位置已经是位置`0`，我们不能将其用作另一个交换的目的地而不将其移走。 什么时候`n >= 3`，我们可以简单地交换位置`1`和`2`。 位置`0`保持不变，所以它仍然给出`a[0] > b[0]`。 这也满足了恰好执行一次交换的要求。 

仅有的`n = 2`当有利位置已经是第一时需要特殊处理。 只有一次可能的交换，因此交换后，旧的第二位置变成了第一位置。 交换恰好在以下时间成功`a[1] >= b[1]`。 如果第二位置是中性的，则新的第一位置相等并且有利的货币对移动到第二位置。 如果第二位置也有利，则第一位置仍然有利。 如果不利，则最终的第一位置使`a < b`。 

观察结果将整个问题简化为对某个位置进行一次扫描`a[i] > b[i]`，加上恒定的工作量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(n) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.从左到右扫描字符串并找到任意索引`p`这样`a[p] > b[p]`。 如果不存在这样的索引，则输出`NO`。 互换仅在头寸之间移动现有货币对，因此如果最初不存在的话，它永远无法创建有利的货币对。 
2.如果`p > 0`, 输出位置`1`和`p + 1`。 交换后，这对原本处于`p`移动到第一个位置，给出`a[0] > b[0]`。 结果字符串立即排序`a`大于`b`。 
3.如果`p = 0`和`n >= 3`, 输出位置`2`和`3`。 第一个位置没有被触及，所以严格不平等`a[0] > b[0]`仍然是第一个决定性的比较。 交换仍然执行，因为该问题只需要一项操作。 
4.如果`p = 0`和`n = 2`，唯一可能的交换是头寸`1`和`2`。 在这次交换之后，原来的第二位置变成了第一位置。 准确地接受交换`a[1] >= b[1]`; 否则输出`NO`。 

解决方案背后的不变量是位置的比较关系与其对一起移动`(a[i], b[i])`。 每当我们将已知的有利对移动到第一个位置时，它就成为第一个决定性比较并证明`a > b`。 当有利的对已经是第一个时，我们可以通过交换两个后面的位置来保留它，前提是存在两个这样的位置。 唯一不可能的情况是`n = 2`，必须直接检查唯一的替代方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = input().strip()
    b = input().strip()

    pos = -1

    for i in range(n):
        if a[i] > b[i]:
            pos = i
            break

    if pos == -1:
        print("NO")
        return

    if pos > 0:
        print("YES")
        print(1, pos + 1)
        return

    if n >= 3:
        print("YES")
        print(2, 3)
        return

    # n == 2 and the favorable position is already position 1.
    if a[1] >= b[1]:
        print("YES")
        print(1, 2)
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```扫描存储第一个位置`a[i] > b[i]`。 任何这样的位置就足够了，因为如果它还不是第一个，将其移动到第一个位置会立即解决字典比较问题。 

这`pos > 0`分支使用从零开始的 Python 索引，但打印从一开始的位置。 因此位置`0`变成`1`， 尽管`pos`变成`pos + 1`。 

什么时候`pos == 0`和`n >= 3`, 职位`1`和`2`从零开始的索引对应于输出位置`2`和`3`。 它们被保证存在，因为`n >= 3`，都不影响有利的第一位置。 

最终分支仅到达`n == 2`。 正好有一个合法的交换，所以检查一下`a[1] >= b[1]`就足够了。 接受相等是因为交换后第一个字符可能相等，从而允许来自原始第一个位置的有利对决定第二个字符处的比较。 

不需要字符串复制或更改。 该算法仅确定一对有效的索引，因此额外的内存使用量是恒定的。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 字符串被扫描一次以找到一个位置`a[i] > b[i]`。 |
 | 空间| O(1) | O(1) | 仅存储输入字符串和恒定数量的索引； 没有额外的结构依赖于`n`。 |

 和`n <= 10^5`，一次线性扫描仅执行大约十万个字符比较，这很容易在 1 秒的限制之内。 该算法还使用恒定的辅助空间，远低于 256 MB 内存限制。

import sys
import io
from contextlib import redirect_stdout

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = input().strip()
    b = input().strip()

    pos = -1

    for i in range(n):
        if a[i] > b[i]:
            pos = i
            break

    if pos == -1:
        print("NO")
        return

    if pos > 0:
        print("YES")
        print(1, pos + 1)
        return

    if n >= 3:
        print("YES")
        print(2, 3)
        return

    if a[1] >= b[1]:
        print("YES")
        print(1, 2)
    else:
        print("NO")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    output = io.StringIO()

    try:
        sys.stdin = io.StringIO(inp)
        with redirect_stdout(output):
            solve()
    finally:
        sys.stdin = old_stdin

    return output.getvalue()

# Provided samples
assert run("""3
abc
abc
""") == "NO\n", "sample 1"

assert run("""3
zzz
aaa
""") == "YES\n2 3\n", "sample 2"

# Minimum size, favorable position is second.
assert run("""2
ab
aa
""") == "YES\n1 2\n", "minimum size with favorable second position"

# Minimum size, favorable position is first but the second position is unfavorable.
assert run("""2
ba
ab
""") == "NO\n", "minimum size impossible case"

# All positions equal.
assert run("""4
abcd
abcd
""") == "NO\n", "all-equal strings"

# Maximum size, favorable position is the final character.
n = 100000
a = "a" * (n - 1) + "b"
b = "a" * n
assert run(f"{n}\n{a}\n{b}\n") == f"YES\n1 {n}\n", "maximum size and last position"

# Favorable position is first, with exactly three positions.
assert run("""3
baa
abb
""") == "YES\n2 3\n", "favorable first position"

 | --- | --- | --- |
 |`2 / ab / aa`|`YES / 1 2`| 有利对位于第二位置的最小长度。 |
 |`2 / ba / ab`|`NO`| 特别的`n = 2`唯一交换的情况`a < b`。 |

 ## 边缘情况

 ### 没有有利的位置

 考虑```
3
abc
abd
```每个位置都满足`a[i] <= b[i]`。 扫描结束时没有找到有利的对，因此`pos = -1`算法打印`NO`。 由于交换仅重新定位现有的字符对，因此任何操作都无法使更大的字符出现在`a`比在`b`处于以前不可能的位置。 

### 有利位置已是第一名并且有三个或更多位置

 考虑```
3
baa
abb
```在位置`1`,`b > a`，所以扫描发现`pos = 0`。 由于至少有三个位置，因此算法选择位置`2`和`3`。 第一对仍然存在`(b, a)`，所以得到的字符串仍然满足`a > b`立即出现在他们的第一个字符处。 所需的交换仅更改后面的位置。 

### 有利位置先有两个位置

 考虑```
2
ba
ab
```第一个位置有`b > a`，但第二个有`a < b`。 自从`n = 2`，唯一合法的操作是交换两个位置。 结果变成`ab`和`ba`，其第一个字符满足`a < b`。 算法检查`a[1] >= b[1]`, 发现`a < b`，并正确打印`NO`。 

对比案例```
2
ba
aa
```有`b > a`在第一个位置并且`a = a`在第二次。 交换后，字符串变成`ab`和`aa`。 第一个字符相等，第二个比较是`b > a`，所以结果有效。 该算法接受是因为`a[1] >= b[1]`。 

###最终指数的有利位置

 考虑```
4
aaab
aaaa
```唯一有利的位置是指数`4`， 在哪里`b > a`在字符串的表示法中，特别是`b > a`。 从零开始扫描发现`pos = 3`。 交换位置`1`和`4`将有利的对移到前面，产生第一个字符的比较`b > a`。 算法输出`YES 1 4`。 

本案例锻炼了`pos + 1`转换并说明了为什么任何远离前方的有利位置都可以直接移到前方。
