 ## 解决方案
 ## 问题理解

 想想每棵树上次受到攻击的时间。 如果一棵树在一年后重置`t`，那么它的增长正好是`m - t`几年后，所以它的最终高度是`m - t`。 等价地，定义

 [
 t_i = m-h_i。 
]

 价值`t_i`是树的最后重置时间`i`。 值为`0`意味着该树从未受到攻击，或者在种植后立即受到攻击。 唯一的全局要求是某处至少发生一次攻击。 

在特定的重置时间`t`，每棵树的最终重置时间小于`t`已经完成并且不能包含在时间间隔中`t`，因为这样做会在以后进行最终重置。 至少具有最终重置时间的树`t`仍然可用。 在这些可用位置中，所有最终重置时间恰好为`t`必须被时间所使用的间隔覆盖`t`。 

这将问题转化为区间连通性问题。 对于每个`t`，考虑所有满足条件的位置`t_i >= t`。 它们形成几个不相交的连续组件。 如果一个组件至少包含一个位置`t_i = t`，该组件内部至少需要一个攻击间隔。 让`c_t`是此类组件的数量。 那么每个有效的解决方案都必须有

 [
 k \ge \max_t c_t。 
]

 还有第二个限制。 每次攻击的时间`t`必须准确包含`k`非空区间，并且可用位置的数量与具有的树的数量一样多`t_i >= t`。 最小的这样的集合出现在最大的复位时间，因此最强的限制是`k`不能超过最大树数`t_i`。 自从`t_i=m-h_i`，这正是具有最小最终高度的树木的数量。 

因此，如果

 [
 K=\max_t c_t
 ]

 和`freq_min`是高度最小的树的数量，答案是`K`什么时候`K <= freq_min`， 和`-1`否则。 

输入大小是实现需要线性的主要原因。 对于最多 (10^6) 棵树，即使是 (O(n\log n)) 工作也比单次扫描要昂贵得多，而 (O(n^2)) 意味着最多 (10^{12}) 个基本操作。 年数可以达到（10^9），因此无论数组操作多么小，每年迭代的算法都是不可能的。 解决方案必须取决于位置及其高度，而不是取决于数字的大小`m`。 

在很多情况下，直接解释可能会出错。 如果每个高度都是`m`， 例如`n=4, m=3`有高度`3 3 3 3`，答案是`1`， 不是`0`。 阿尤布需要至少攻击一次，并且他可以在种植后立即攻击，因此一个间隔覆盖所有四棵树是有效的。 

如果相同的最终重置时间出现在两个分开的位置，则它们不一定需要两个间隔。 为了`n=3, m=2`和高度`1 0 1`，复位时间为`1 2 1`。 两棵树同时重置`1`可以被包含所有三个位置的一个区间覆盖。 然后中间的树再次受到攻击`2`。 答案是`1`。 一个粗心的解决方案只是简单地计算相同高度的运行将错误地返回`2`。 

还有一些真正不可能的配置。 考虑`n=5, m=3`有高度`2 1 2 0 2`。 重置时间为`1 2 1 3 1`。 时`2`, 两个位置有复位时间`2`是分开的，所以需要两个间隔。 因此`k`必须至少是`2`。 但有时`3`仍然只能攻击一棵树，因此不可能出现恰好两个非空区间。 正确答案是`-1`。 

## 方法

 一个简单的解决方案可以独立检查每个可能的重置时间。 对于固定的`t`，扫描整个数组并确定仅由具有的位置组成的分量`t_i >= t`，然后计算其中有多少个组件包含以下位置`t_i=t`。 对每个不同的值重复此操作`t`给出所有必需的`c_t`价值观。 在最坏的情况下，有 (n) 个不同的重置时间，每次扫描成本为 (O(n))，给出 (O(n^2))，或者 (n=10^6) 进行多达 (10^{12}) 次数组检查。 这远远超出了一秒的限制。 

蛮力之所以有效，是因为真正的问题正是应用阈值后连接的组件。 问题在于，显式重建这些阈值组件会浪费几乎所有的工作。 当阈值改变一个值时，大部分数组结构不会改变。 

关键的观察结果是阈值分量可以用笛卡尔树表示。 使用原始高度而不是重置时间会稍微干净一些。 重置时间`t`，条件`t_i >= t`相当于

 [
 h_i \le m-t。 
]

 所以我们需要子数组级集合的连通分量的数量`h_i <= H`其最大值恰好是`H`。 最大笛卡尔树精确地表示这些嵌套组件。 其父节点具有严格更大高度的每个节点都代表一个组件，其最大值为该节点的高度。 

单调递减堆栈在线性时间内构造相关的笛卡尔树结构。 当新高度到达时，堆栈上所有较小的高度都会成为新值的子高度。 如果在删除这些较小的值后，堆栈为空或其顶部严格小于新值，则新节点将在其自己的高度开始一个新组件，因此我们会增加该高度的计数。 等高保持在一起，这一点很重要，因为当没有更小的高度将它们分开时，等高位置属于相同的阈值分量。 

结果计数给出了每个`c_t`无需显式构建一棵树。 我们只需要一个从高度到其分量根数的字典。 同时，我们跟踪最小高度频率，它提供了上界`k`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 阈值扫描| (O(n^2)) | (O(n)) | (O(n)) | 太慢了 |
 | 单调堆栈| (O(n)) 摊销 | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1. 读取最终高度并找出最小高度以及有多少棵树具有该高度。 最小高度对应于最大重置时间，即仍然有资格受到攻击的树木最少的年份。 因此，它给出了上限`k <= freq_min`。 
2. 以非递增顺序维护一堆高度。 该堆栈表示到目前为止处理的前缀的最大笛卡尔树的右边界链。 相同的值保留在堆栈中而不是被删除。 
3. 对于每个高度`x`，删除每个小于的堆栈值`x`。 每个被移除的节点刚刚找到了一个严格更大的祖先，即`x`。 这正是使该节点成为一个阈值分量的最大值的关系。 当节点被压入时，计数可以与该节点相关联，因为在删除所有较小的值之后，其当前的堆栈父级是笛卡尔树父级。 
4. 删除所有较小的值后，检查新的堆栈顶部。 如果堆栈为空或者其顶部严格小于`x`，增加与关联的组件计数`x`。 如果顶部等于`x`，不要增加它，因为新出现的值与现有的相等值属于相同的阈值分量。 
5. 推`x`到堆栈上。 每个高度被压入一次，最多弹出一次，所以整个堆栈过程是线性的。 
6.让`k`是针对任何高度存储的最大组件数。 这是任何攻击年份所需的最小间隔数。 如果`k > freq_min`， 打印`-1`，因为在最近的攻击年没有足够的树木来形成`k`非空间隔。 否则打印`k`。 

### 为什么它有效

 对于任何阈值`H`, 高度最大的位置`H`形成连续的组件。 其最大值恰好为的分量`H`对应于攻击时必须处理的一组可能的树`m-H`。 每个这样的分量至少需要一个区间，因此这些分量的数量是`k`。 

最大笛卡尔树恰好组织了这些组件。 具有严格更大父级的节点是处于其自身高度的组件的根。 相等的父值和子值故意不单独计算，因为它们在该阈值属于同一组件。 单调堆栈在不显式构建树的情况下维护这种父关系，因此字典计数正是值`c_t`。 

取这些计数中的最大值给出可能的最小值`k`满足所有下界。 唯一剩下的问题是在每个所需的攻击时间是否可以存在那么多非空间隔。 随着重置时间的增加，符合条件的树的数量会减少，因此最紧的情况是最大重置时间，它对应于最小最终高度。 如果它的频率至少为`k`，每个较早的攻击时间至少有同样多的合格树，并且可以通过根据需要分割合格的分量来形成所需的间隔。 因此`k <= freq_min`既是必要的又是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    min_h = min(a)
    freq_min = 0

    counts = {}
    stack = []
    answer = 0

    for x in a:
        if x == min_h:
            freq_min += 1

        while stack and stack[-1] < x:
            stack.pop()

        if not stack or stack[-1] < x:
            counts[x] = counts.get(x, 0) + 1
            if counts[x] > answer:
                answer = counts[x]

        stack.append(x)

    if answer > freq_min:
        print(-1)
    else:
        print(answer)

solve()
```对输入的第一次扫描同时确定最小高度频率并构造单调堆栈。 变量`freq_min`是在最晚可能的重置时间仍然可以被攻击的树的数量。 

堆栈按降序维护。 什么时候`x`到达时，每个较小的值都会被删除，因为`x`是右侧第一个严格更大的值，并成为其相关的笛卡尔树祖先。 一旦这些较小的值被删除，`x`当堆栈中紧邻其上方没有等高值时，恰好启动一个新组件。 

严格的比较是微妙的部分。 使用`<=`在弹出条件下会将相等的高度拆分为单独的笛卡尔树组件，并且会错误地计算高度等配置`1 2 1`。 相等的值必须在其阈值处保持连接。 

Python 整数具有任意精度，因此不存在溢出问题。 最大答案是最多`n`，即 (10^6)。 字典最多可以包含`n`不同的高度，并且堆栈还可以包含最多`n`条目，符合所述约束的内存限制。 

## 工作示例

 对于示例 1，输入为`n=4, m=3`所有高度都是`3`。 最小高度为`3`， 所以`freq_min=4`。 堆栈永远不会遇到严格更大的值，并且第一个`3`启动一个组件。 

| 索引 | 高度| 堆栈之前 | 弹出 | 高度的组件数量 | 堆栈之后 |
 | ---| ---| ---| ---| ---| ---|

 | 2 | 3 |`[3]`| 无 |`c[3]=1`|`[3,3]`|

 最大元件数为`1`， 和`1 <= 4`，所以答案是`1`。 这也说明了为什么相等的高度不能被算作单独的阈值分量。 

对于示例 2，输入为`n=4, m=3`所有高度都是`0`。 这里`freq_min=4`。 第一个零开始一个组件，其余相等的值扩展它。

 同样，最大组件数为`1`，所以答案是`1`。 就原来的流程而言，阿尤布可以在种植后立即攻击所有四棵树，并让它们生长三年。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(n)) 摊销 | 每个高度都被压入一次并最多从堆栈中删除一次。 预计会进行字典操作 (O(1))。 |
 | 空间| (O(n)) | (O(n)) | 在最坏的情况下，输入数组、单调堆栈和高度计数字典都使用线性空间。 |

 对于 (n\le10^6)，线性扫描是合适的目标。 该算法不会迭代潜在的巨大价值`m`， 所以`m`大到 (10^9) 对运行时间没有影响。 堆栈操作是线性摊销的，因为一个元素不能多次弹出。

 ## 边缘情况

 全高-`m`情况是`4 3`有高度`3 3 3 3`。 复位时间数组是`0 0 0 0`。 堆栈创建一个高度组件`3`因为所有平等的价值观都在一起。 答案是`1`。 这是有效的，因为单次攻击可能在种植后立即发生。 

全高度为零的情况是`4 3`有高度`0 0 0 0`。 复位时间数组是`3 3 3 3`，因此所有树木都必须在最后一年受到攻击。 它们形成一个连续的组件，需要一个间隔。 最小高度出现四次，所以`freq_min=4`，答案是`1`。 

分离等高案例`3 2`有高度`1 0 1`产生复位时间`1 2 1`。 在较早的攻击时间，重置时间的两棵树`1`位于一个组件中，因为可以包含中间树，并且稍后将再次重置。 笛卡尔堆栈高度计数`1`因此是一，而不是二。 后面的重置时间只有中间的树，所以`k=1`作品。 

不可能的情况`5 3`有高度`2 1 2 0 2`产生复位时间`1 2 1 3 1`。 复位时`2`，位置二和位置四是树中的独立组件，其最终重置至少为`2`, 强迫`k>=2`。 复位时`3`，只有位置四有最终重置时间，因此只有一棵符合条件的树，无法形成两个非空区间。 该算法计算的最大组件数为`2`和最小高度频率`1`，检测到`2 > 1`，并打印`-1`。 

平等边界也很重要。 对于高度`0 1 0 1`, 最大高度`1`发生在两个独立的组件中，因此所需的`k`是`2`。 最小高度`0`也发生两次，在最近的重置时间恰好给出两棵符合条件的树。 由于下限和上限相交，所以答案正是`2`。
