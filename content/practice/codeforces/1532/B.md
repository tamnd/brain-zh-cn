 ## 解决方案
 ## 问题理解

 青蛙从位置 0 开始沿直线数轴移动。它的运动是完全确定性的：它在两个固定步长之间交替。 第一次移动时，它会按距离向右移动`a`，在第二次移动时，它向左移动`b`，然后就由`a`再次，然后离开`b`，依此类推，直到执行`k`跳跃。 

每个查询都是独立的，对于每个查询，我们都需要精确之后的最终坐标`k`这样的交替跳跃。 

约束条件`k ≤ 10^9`立即排除逐步模拟每次跳跃的可能性。 尽管每个操作都是简单的加法或减法，但每个查询执行多达十亿次操作将超出任何实际的时间限制。 对于多达 1000 个查询，在最坏的情况下，简单的模拟将达到 10^12 次操作，这是不可行的。 

关键的困难不仅仅在于计算复杂性，还在于认识到运动模式是周期性的，周期为 2，因此该过程可以压缩为计算完整的运动对。 

一个常见的错误来自于对最后一对不完整的动作处理不当。 例如，当`k = 1`，只有初始的`+a`应该应用，并且不会发生减法。 什么时候`k = 2`，净运动是`a - b`。 什么时候`k = 3`，就变成`a - b + a`， 等等。 任何仅假设完整对的方法（即`k // 2 * (a - b)`) 将因奇数而失败`k`如果它不考虑额外的向前跳跃。 

另一个微妙的问题是具有固定宽度整数的语言中的整数溢出。 自从`a, b, k`可以达到`10^9`，中间值如`k * a`可以达到`10^18`，这需要 64 位或 Python 的任意精度整数。 

## 方法

 蛮力方法直接模拟青蛙的跳跃。 从位置 0 开始，从 1 迭代到`k`，添加`a`奇数步和减法`b`on even steps. 这是正确的，因为它完全遵循定义。 然而，它的成本是线性的`k`，因此在所有查询中可能需要最多 10^12 次操作，这远远超出了可行的限制。 

关键的观察结果是跳跃是成对重复出现的：`( +a, -b )`。 每对完整的贡献净运动`a - b`。 如果我们将序列分组为完整的对，我们得到`k // 2`这样的对。 剩下的就是可能的额外第一步，如果`k`很奇怪。 那个额外的动作总是`+a`。 

因此，整个过程简化为计算存在多少个完整对以及是否需要一次额外的前向跳跃。 这消除了所有迭代并将每个查询减少为常数时间算术。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每次查询 O(k) | O(1) | O(1) | 太慢了|
 | 最佳 | 每个查询 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取整数`a`,`b`， 和`k`对于每个查询。 这些定义了要模拟的步长和移动数量。 
2. 使用以下公式计算存在多少个完整的两步循环`k // 2`。 每个周期包含一个`+a`和一个`-b`，因此它贡献的净位移为`a - b`。 
3. 将完整周期数乘以`(a - b)`获得所有配对动作的贡献。 这会将所有偶数索引行为压缩为一个算术表达式。 
4. 如果`k`为奇数，再加一个`+a`来解释最后一次不成对的向前跳跃。 这是必要的，因为序列总是以向前一步开始​​。 
5. 输出结果总和。 

### 为什么它有效

 在考虑第一个移动之后，移动序列是严格周期性的，长度为 2。 每对`( +a, -b )`具有独立于仓位或历史的固定净效应。 由于加法是结合的，因此将运算分组为不相交的对不会改变最终结果。 唯一的例外是当序列长度为奇数时，在这种情况下，最终的未配对操作始终是初始操作`+a`步。 这保证了公式准确地重建了在 处截断的无限交替序列的完整前缀和。`k`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
out = []

for _ in range(t):
    a, b, k = map(int, input().split())
    
    pairs = k // 2
    ans = pairs * (a - b)
    
    if k % 2 == 1:
        ans += a
    
    out.append(str(ans))

print("\n".join(out))
```该解决方案直接实现派生分解。 表达式`pairs * (a - b)`编码所有完整的循环，而条件`if k % 2 == 1`处理剩余的第一次跳转。 结果以字符串形式累积，以避免循环内重复的 I/O 开销。 

需要小心维护正确的操作顺序：计算`k // 2`首先避免重复划分、分组`(a - b)`确保我们不会意外地混合来自不同步骤的贡献。

 这显示了完整的一对加上额外的向前跳跃。 公式给出`k // 2 = 1`， 所以`1 * (5 - 2) = 3`，加上额外的`5`, 给予`8`。 

这证实了分解处理奇数`k`正确。 

### 示例 2

 输入：`a = 100, b = 1, k = 4`| 步骤| 行动| 贡献 | 职位|

 有两对完整的对，每对都有贡献`99`，所以总计是`198`。 此后不存在剩余跳跃`k`是均匀的。 

这证实了配对逻辑无需显式模拟即可完全捕获重复结构。

 ## 边缘情况

 当`k = 1`，算法计算`k // 2 = 0`，因此该对贡献为 0 并且因为`k`很奇怪它添加了`a`。 例如`a = 7, b = 2, k = 1`产生`7`，匹配单跳定义。 

什么时候`a = b`，每对完整的净运动贡献为零。 为了`a = 3, b = 3, k = 5`，我们得到两对完整的对，给出 0 和一个额外的`+3`， 导致`3`，它匹配显式序列`3 - 3 + 3 - 3 + 3`。 

什么时候`k`均匀且大，例如`k = 10^9`，所有运动都被捕获`k // 2`对。 除了整数乘法之外，不需要特殊处理，因为 Python 自然支持大整数并且公式保持稳定。
