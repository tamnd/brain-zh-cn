 ## 解决方案
 ## 问题理解

 我们在一个非常具体的约束下构建字符串：每个字符串必须仅使用前 k 个小写拉丁字母，并且这 k 个字母中的每一个都必须至少出现一次。 在所有长度为 n 的有效字符串中，我们希望使最不常见的字符尽可能大。 

简单来说，我们将 n 个相同的位置分布在 k 个标记桶（字母 a 到第 k 个字母）中，条件是没有桶是空的。 在所有这些分布中，我们希望最大化最小桶大小。 确定计数后，我们可以按任意顺序排列字符以形成有效的字符串。 

约束很小：n 和 k 最多为 100，并且最多有 100 个查询。 这立即告诉我们，每个查询的任何 O(nk) 甚至 O(n²) 构造都是微不足道的。 真正的任务不是效率，而是识别正确的分配策略。 

当一个人试图“贪婪地传播字母”而不强制平衡时，就会出现一个幼稚的错误。 例如，如果 n = 7 且 k = 3，粗心的方法可能会分配 3, 2, 2 或 4, 2, 1，而不考虑最优性。 正确答案需要尽可能均衡频率，同时保持所有 k 个字母都存在。 

另一种常见的失败模式是忘记“每个字母至少一次”约束。 例如，对于 n = 4、k = 4，唯一有效的分布恰好是每个字母之一。 任何将最小频率最大化到超过 1 的尝试都会违反可行性，因为除了确保存在之外没有额外的空间。 

该问题从根本上讲是关于每组下限为 1 的整数划分以及最大化最小组大小。 

## 方法

 暴力方法会尝试所有方法将计数分配给 k 个字母，使得每个计数至少为 1 并且总和为 n。 对于每个作业，我们计算最小计数并跟踪最佳结果。 此类分区的数量像整数的组合一样增长，大约为 O(C(n-1, k-1))，通常以 k 为指数，因此即使 n 很小，也是不可行的。 

关键的观察是只有平衡的分布才重要。 如果我们最大化最小频率，我们希望所有 k 个字母的计数尽可能接近。 假设我们尝试让每个字母出现 x 次。 这会消耗 kx 个字符。 剩余的 n − kx 个字符可以任意分布，增加一些频率，但永远不会降低低于 x 的最小值。 因此，最好的 x 就是满足 kx ≤ n 的最大整数，即 x = n // k。 

分配完这个基本数量后，还有 r = n % k 剩余字符。 这些剩余的内容可以在任何 r 字母中每个字母分布一个，从而增加它们的频率但保留结构。 这产生了最小频率最大化的有效结构。 

因此，我们不进行搜索，而是直接计算最佳基频，然后确定性地构造字符串。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | k 的指数 | O(k) | 太慢了|
 | 最佳 | 每个查询 O(n) | O(n) | 已接受 |

 ## 算法演练

 对于每个查询，我们独立构造字符串。

1. 计算基频为 x = n // k。 这是我们可以保证每个字母至少出现 x 次且总共不超过 n 的最大次数。 
2. 计算余数 r = n % k。 这表示每个字母出现 x 次后将分配的额外字符。 
3. 创建一个空的字符列表。 
4. 对于前 k 个字母中的每一个，将该字母精确地附加到结果 x 次。 这保证了每个必需的字母都存在并设置了基线最小频率。 
5. 通过获取前 r 个字母并在每个字母后附加一个额外的出现来分配剩余的 r 个字符。 这会增加一些频率，但不会减少任何低于 x 的频率。 
6. 将列表连接成最终字符串并输出。 

关键的设计选择是，只要我们保持有效性，剩余物的分配是任意的。 将剩余部分分配给前 r 个字母是确保正确性的一种方便的确定性方法。 

### 为什么它有效

 该结构保证每个字母至少出现 x 次，因此最小频率至少为 x。 由于将 x 赋予 k 个字母中的每一个所使用的字符总数为 kx ≤ n 并且 x = n // k 是此属性的最大值，因此没有解决方案可以实现大于 x 的最小频率。 任何将最小值增加到 x + 1 的尝试都需要至少 k(x + 1) > n 个字符，这是不可能的。 因此，该结构是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())

    x = n // k
    r = n % k

    res = []

    for i in range(k):
        res.append(chr(ord('a') + i) * x)

    for i in range(r):
        res[i] += chr(ord('a') + i)

    print(''.join(res))
```代码直接遵循分发逻辑。 第一个循环初始化基本统一块，其中每个字母都有 x 个副本。 第二个循环通过增加前 r 个字母来处理剩余的内容。 

一个微妙的点是，剩余的赋值会修改已经构造的字符串，这是安全的，因为字符串很小（n ≤ 100）。 另一种有效的替代方法是首先构建频率数组，然后对其进行扩展，但在约束条件下直接字符串连接更简单。 

## 工作示例

 考虑 n = 7，k = 3。 

我们计算 x = 7 // 3 = 2 且 r = 1。

## 测试用例```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        x = n // k
        r = n % k

        res = []

        for i in range(k):
            res.append(chr(ord('a') + i) * x)

        for i in range(r):
            res[i] += chr(ord('a') + i)

        out.append(''.join(res))

    return '\n'.join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# custom cases

assert run("1\n5 2\n") is not None
assert run("1\n100 1\n") is not None
assert run("1\n3 3\n") is not None

 ## 边缘情况

 对于 n = k，每个字母必须恰好出现一次。 该算法计算 x = 1 且 r = 0，因此不会发生额外的分布。 输出是前 k 个字母的简单排列，这是有效且最佳的，因为最小频率不能超过 1。 

当 n < 2k 时，基频变为 1，剩余部分稀疏。 该算法仍然确保每个字母至少出现一次，并安全地分配额外的字符，而不会破坏平衡。
