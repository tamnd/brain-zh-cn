 ## 解决方案
 ## 问题理解

 我们得到了一系列独立的查询。 每个查询由两个整数组成，对于每一对，我们必须计算它们的算术和并立即输出。 

测试用例之间不存在依赖关系。 每对都可以单独处理，因此问题简化为重复应用单个恒定时间操作。 

这些约束允许最多 10,000 个测试用例，每个整数范围在 -1000 到 1000 之间。这意味着值的大小足够小，以至于在 Python 中整数溢出不是问题，即使在较低级别的语言中，32 位整数也足够了。 主要因素是所有测试用例的操作数量。 

天真的解释可能会建议在处理之前构建中间结构或存储所有输入，但问题中没有任何要求。 任何比每个测试用例持续工作更多的方法仍然会通过这里，但这将是不必要的开销。 

边缘情况很少，但仍然值得承认。 一个常见的错误是错误处理负值或忘记为每个测试用例输出换行符。 

例如，输入：```
1
-1000 1000
```正确的输出是：```
0
```粗心的实现可能会尝试字符串连接而不是数字加法并产生`-10001000`，这是不正确的，因为它将输入视为字符串而不是整数。 

## 方法

 暴力解释是读取每个测试用例，使用标准算术计算总和，然后打印它。 由于每个操作的时间复杂度为 O(1)，因此总工作量与测试用例的数量呈线性关系。 

除了直接计算之外，没有任何结构可供利用。 没有前缀重用，没有排序，没有图遍历。 问题本质上是对输入管道和输出格式是否正确的健全性检查。 

唯一有意义的“优化”是确保快速输入解析并避免循环内不必要的转换或字符串操作。 因此，最佳解决方案在算法结构上与暴力方法相同，仅在实现清洁度和 I/O 效率方面有所不同。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力（每个测试用例直接求和）| O(t) | O(1) | O(1) | 已接受 |
 | 最优（快速 I/O + 直接求和）| O(t) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取整数`t`，它定义了我们必须执行多少次独立加法。 这决定了主循环中的迭代次数。 

2. 对于每个测试用例，读取两个整数`a`和`b`来自输入。 解析步骤确保我们将值解释为数字而不是字符串，因此算术行为正确。 

3. 计算总和`a + b`。 这是每个测试用例所需的唯一转换，并且直接对应于问题陈述。 

4. 立即打印结果，确保每个输出出现在自己的行上以保留所需的格式。 

### 为什么它有效

 每个测试用例都是独立的，并定义一个算术表达式。 加法运算是确定性的并且没有副作用。 因为我们只计算并输出每个结果一次，所以该算法保留了输入和输出之间的一对一映射。 测试用例之间没有隐藏状态或交互，因此正确性直接来自整数加法的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    out = []
    for _ in range(t):
        a, b = map(int, input().split())
        out.append(str(a + b))
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```该解决方案使用快速缓冲 I/O 读取输入，这在处理多达 10,000 行时非常重要。 每行被分成两个整数，它们的总和被附加到输出列表中。 在打印之前累积结果的决定避免了重复的昂贵的写入操作。 

一个常见的错误是使用循环内打印`print`，这里仍然可以接受，但在严格约束下速度较慢。 另一个潜在的问题是忘记将输入字符串转换为整数，这将导致字符串连接而不是数字加法。

 | 测量| 复杂性 | 说明|

## 测试用例```python
import sys, io

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        a, b = map(int, input().split())
        out.append(str(a + b))
    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# provided samples
assert run("4\n1 5\n314 15\n-99 99\n123 987\n") == "6\n329\n0\n1110"

# minimum input
assert run("1\n0 0\n") == "0"

# all negative
assert run("2\n-1 -2\n-1000 -1000\n") == "-3\n-2000"

# mixed signs
assert run("3\n1 -1\n10 -3\n-7 20\n") == "0\n7\n13"

# boundary values
assert run("2\n1000 1000\n-1000 1000\n") == "2000\n0"
```| 测试输入| 预期产出 | 它验证了什么 |

 ## 边缘情况

 最简单的边缘情况是两个数字都为零时。 输入：```
1
0 0
```该算法读取两个整数，计算`0 + 0`，和输出`0`。 不需要特殊的分支，并且与所有其他情况一样适用相同的逻辑。 

另一种情况涉及约束范围内的极值，例如：```
1
-1000 1000
```这里总和恰好为零。 由于该算法执行直接整数加法，因此 Python 中不存在溢出或精度损失的风险，并且输出保持正确，无需任何额外处理。
