 ## 解决方案
 ## 问题理解

 我们有偶数个学生，每个学生都有一定的编程技能水平。 目标是准确地形成$n/2$小组，每组由两名学生组成。 仅当两个学生具有相同的技能水平时，团队才有效。 为了实现这一目标，学生可以解决问题，每个问题都会增加他们的技能。 

输入包括$n$（学生人数）和代表技能的整数数组。 输出是一个整数：学生需要解决的最小问题总数，以便每个学生都被配对到一个技能相同的团队中。 

限制很小：$2 \le n \le 100$和$1 \le a_i \le 100$。 和$n$上限为 100，任何算法最多$O(n^2 \log n)$或者$O(n^2)$会在规定的时间内舒适地运行。 这表明即使成对比较方法也是可行的，但我们应该追求更简单、更直接的方法。 可能导致简单解决方案失败的边缘情况包括具有多个重复项或所有唯一值，其中最少数量的问题可能需要不明显的配对。 

一种粗心的方法是简单地将学生按输入顺序配对。 例如，使用输入`4\n1 3 2 2`, 配对`(1,3)`和`(2,2)`会花费`2`对于第一对，但更好的解决方案是`(1,2)`和`(2,3)`仅需花费`1`。 这表明配对顺序很重要。 

## 方法

 暴力方法会考虑每一个可能的配对$n$学生。 有$(n-1)!!$形成对的方法（双阶乘），这在增长中是阶乘，即使对于$n=20$。 在每次配对时，我们都会计算平衡技能的成本。 这种方法原则上是正确的，但计算上不可行。 

关键的观察是，使两名学生平等的成本仅取决于他们技能的绝对差异。 这表明，如果我们按技能对学生进行排序，将相邻的学生配对可以最大限度地降低成本。 排序确保配对学生之间的差异尽可能最小，任何其他配对只会增加差异之和。 排序后，最佳策略是将第一个学生与第二个学生配对，第三个学生与第四个学生配对，依此类推。 这将问题减少到$O(n \log n)$用于排序加$O(n)$用于求和差异。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O((n-1)!!) | O((n-1)!!) | O(n) | 太慢了|
 | 最优（排序+相邻对）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读$n$以及一系列的技能$a$。 排序需要一个允许排序的数据结构； 一个清单就足够了。 
2. 对数组进行排序$a$按非递减顺序。 这确保了连续元素之间的差异最小化。 
3. 初始化变量`total_cost`为零。 这将积累需要解决的问题的数量。 
4. 分两步迭代数组，配对$a[i]$和$a[i+1]$。 对于每一对，计算成本为$a[i+1] - a[i]$并将其添加到`total_cost`。 按排序顺序配对可保证总成本最小。 
5.处理完所有对后，输出`total_cost`。 

为什么有效：排序后，每个学生都会被分配到最接近技能水平的学生。 任何对学生进行交叉配对的尝试都会用较大的差异代替较小的差异，从而增加所需问题的总数。 不变的是，排序后，连续的元素形成全局最优的最小差异对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
a.sort()

total_cost = 0
for i in range(0, n, 2):
    total_cost += a[i+1] - a[i]

print(total_cost)
```解决方案从有效读取输入开始。 排序可确保最小的成对差异。 该循环以两步迭代以正确形成对。 计算`a[i+1] - a[i]`直接给出了每个团队需要的问题数量。 重复或相同技能等边缘情况需要零问题，减法会自动处理这些问题。
