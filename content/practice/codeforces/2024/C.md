 ## 解决方案
 ## 问题理解

 我们给出了几个测试用例，每个测试用例都由一组对组成。 每对的行为就像一个长度为 2 的小块，我们可以任意重新排序这些块。 选择顺序后，我们将所有块连接成一个长度为长的数组$2n$。 

目标不是直接将反转最小化或计算为计数，而是构建块的排列，使得结果数组的最终反转计数尽可能小。 由于输出仅需要一个有效的最优排列，因此这是一个建设性的优化问题，我们必须发现该对的全局排序规则。 

这些约束强制每个测试用例采用线性或更好的解决方案。 所有测试中的总对数最多为$10^5$，因此任何直接比较所有对或重新计算每个排列的反转贡献的解决方案都会立即失败。 解决方案必须为每一对分配一个键并排序一次，或者以其他方式导出避免成对交互的贪婪结构。 

如果我们尝试按字典顺序按值或总和对对进行排序，则会出现微妙的故障模式。 例如，考虑对$[1, 100]$,$[2, 3]$,$[50, 60]$。 按总和或按第一个元素独立排序不会捕获真正的反转贡献，因为反转取决于一个块的第二个元素与另一个块的第一个元素之间的交叉交互。 这种相互依赖性迫使我们采用更具结构性的排序标准。 

## 方法

 暴力解决方案会尝试每一种排列$n$对，构造连接数组，并使用 Fenwick 树或合并排序来计算反转。 这立即给出$O(n! \cdot n \log n)$，即使对于$n = 10$。 

关键的观察结果是，每对以固定的内部顺序恰好贡献了两个元素，并且反转仅以两种方式出现：在一对内部，如果第一个元素大于第二个元素，以及在对之间，取决于它们的四个端点如何交错。 无论排序如何，一对的内部反转成本都是固定的，因此优化仅影响跨对贡献。 

我们将每一对减少为一个结构化的权重，以捕捉提前或推迟放置它的“危险”程度。 正确的贪婪策略来自于通过最小可能的外部反转影响来比较货币对。 直观上，第一个元素较大但第二个元素较小的对应该放置在较晚的位置，因为提前放置时会产生更多反转，而具有较小元素的对应放置在较早的位置，因为它会产生较少的冲突。 

这导致按每对中的最小元素进行排序，并且在平局的情况下将具有较小第二个元素的对放在第一位。 这种排序确保了可能导致未来反转的元素被延迟，而更安全的块被放置在更早的位置。

 ## 算法演练

 1. 对于每一对，根据其两个值计算排序键。 我们选择优先考虑该对中较小的元素，因为它更好地反映了其在放置较早或较晚时引入反转的倾向。 
2. 使用此键对所有对进行排序。 此步骤全局对齐对，以便那些不太可能产生交叉反转的对首先出现，而更多“反转重”的对被推向末尾。 
3. 排序后，按顺序连接对，始终按原始顺序输出每对的两个元素。 这保留了内部结构，同时执行最佳的全局安排。 
4. 输出结果连接数组。 

关键的重要决定是我们永远不会对一对内的元素重新排序。 这是正确的，因为如果该对已经逐渐排序，则在该对内交换只会增加反转，并且仅在减少时减少反转，但该效果是局部的并且独立于其他对。 

### 为什么它有效

 该结构之所以有效，是因为每个反演要么是一对内部的，要么是对之间的交叉。 内部倒置是固定的并且不受排列的影响。 对于交叉反转，一对的贡献仅取决于在其之前出现的较小或较大元素的数量，并且按该对的最小元素排序可确保单调结构，其中较早的对由较小的值主导。 这可以防止后来的大元素被放置在较小的元素之前，从而不必要地增加反转计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    pairs = [tuple(map(int, input().split())) for _ in range(n)]

    pairs.sort(key=lambda x: (min(x), max(x)))

    res = []
    for a, b in pairs:
        res.append(a)
        res.append(b)

    print(*res)
```读取输入后，我们存储所有对并使用字典键对它们进行排序，该字典键优先考虑较小的端点。 这确保了具有较小值的对被放置得更早，这是最小化交叉反转的正确贪婪排序标准。 然后，我们将排序后的对直接展平到输出数组中。 

一个微妙的实现细节是我们不能尝试在一对内任意交换。 尽管交换在本地看起来可能是有益的，但它破坏了与全局排序规则的一致性，并且可能会不可预测地增加交叉反转。 保持内部顺序固定可确保所有优化仅由排序步骤处理。 

## 工作示例

 考虑三对输入$[1,4], [2,3], [3,5]$。 按最小元素排序后，顺序不变$[1,4], [2,3], [3,5]$。 结果数组是$[1,4,2,3,3,5]$。 

| 步骤| 当前对 | 输出数组 |
 | --- | --- | --- |
 | 1 | [1,4]| 1,4|
 | 2 | [2,3]| 1,4,2,3 |
 | 3 | [3,5]| 1,4,2,3,3,5 |

 该轨迹表明，较早放置较小的最小元素可以避免引入反转，即较大的早期值将主导较小的后期值。 

现在考虑对$[5,10], [2,3], [9,6]$。 排序给出$[2,3], [5,10], [9,6]$，生产$[2,3,5,10,9,6]$。 

| 步骤| 当前对 | 输出数组 |
 | --- | --- | --- |
 | 1 | [2,3]| 2,3 |
 | 2 | [5,10]| 2,3,5,10 |
 | 3 | [9,6]| 2,3,5,10,9,6 |

 这演示了较大的对如何被延迟，防止它们出现在较小的值之前，从而产生不必要的反转。

 ## 边缘情况

 单个对的最小输入确认该算法保留对完整性，而不会引入不必要的转换。 在这种情况下，排序很简单，输出必须与输入完全匹配。 

降序结构化输入，例如$[10,1], [9,2], [8,3], [7,4]$强调排序规则是否正确地稳定了序列后期的大优先元素。 该算法将所有对按照其最小端点的升序排列，生成一个序列，避免引入会产生交叉反转的早期大值。 

值对重叠的混合输入确保字典排序足以稳定全局的反演贡献。 该算法自然地解决了这种情况，因为最小的可用起点始终主导较早的放置。
