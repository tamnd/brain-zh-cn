 ## 解决方案
 ## 问题理解

 我们有一个从问题 1 开始并以一种非常不寻常的方式解决问题的过程。 对于每个问题，我们要么提交，要么跳过。 提交会给我们积分，并迫使下一个问题只能从比当前问题严格小的索引中选择。 跳过不会给出分数，但允许系统跳转到索引最多为给定阈值的问题`b[i]`，并且在这些索引中它总是选择最大的未见过的索引。 

一个关键的隐藏结构是参与者永远无法控制简单的从左到右或从右到左的遍历。 相反，每个决策要么在索引空间中严格向下推动进程，要么强制重置为有界前缀，同时还保证每个问题最多被访问一次。 当没有未见的有效问题仍然存在时，该过程最终终止。 

目标是选择每次访问时提交或跳过的策略，以最大化收集的总分。 

约束很大：所有测试用例的问题总数高达 400000 个。这立即排除了任何通过扫描或重复遍历来简单地模拟每步转换的解决方案。 即使每个测试用例有 O(n^2) 行为也是不可能的，甚至 O(n log n) 也必须仔细构建。 

不明显的困难在于，跳过并不简单地移动到`b[i]`，它移动到最大的未见索引`b[i]`，这取决于访问节点的历史记录。 幼稚的实现会重复搜索前缀中的下一个可用索引，这会降级为二次行为。 

当贪婪直觉被错误地应用时，就会出现典型的陷阱。 例如，总是取局部最好的`a[i]`如果可能会失败，因为跳过可以稍后解锁对更大索引的访问，而过早提交可能会立即终止该过程。 

考虑一个小例子：

 输入：

 n = 3

 a = [10, 1, 100]

 b = [1, 2, 2]

 如果我们在 1 处提交，我们立即以 10 结束。但是跳过 1 会将我们发送到 2 或 3，具体取决于状态，最终允许 100。贪婪的“如果现在很大就采取”方法完全错过了这个结构。 

关键是要明白，这个过程从根本上来说是控制我们能够继续探索更高指数的程度，并且提交决策会划分未来的可达区域。 

## 方法

 强力方法将模拟所描述的整个过程。 从当前索引开始，我们尝试两种选择，递归模拟下一个状态，并跟踪最佳分数。 每个状态取决于哪些索引已经被访问过，因此状态空间包括一个访问集。 即使使用记忆化，这也会呈指数增长，因为访问的结构以路径依赖的方式演变，并且有多达 400000 个节点。 

即使我们简化并忽略访问状态的复杂性，每次转换也可能需要找到前缀中最大的未使用索引，除非数据结构支持，否则每一步将花费 O(n) 的时间。 在最坏的情况下，这已经导致每个测试用例的复杂度为 O(n^2)。 

关键的观察是该过程不会自由分支。 每个索引最多被访问一次，并且每次转换要么严格减少索引，要么移动到由下式确定的前缀边界`b[i]`。 这意味着我们可以根据可达索引的片段来思考，其中节点的决策是“使用”它（提交）还是“重定向控制”（跳过）到受约束的前缀。 

这种结构建议在类似函数图的过程上进行贪婪动态编程混合。 系统总是移动到前缀中最大的未见索引，其行为类似于维护活动范围的堆栈。 我们可以使用下一个未访问的结构（索引上的不相交集并集）有效地模拟该过程，确保每个索引都被处理一次。 

然后，我们通过按发现降序处理索引来计算可实现的最佳分数，并使用 DSU 有效地跳转到下一个可用的未访问候选者。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟 | O(2^n) / O(n^2) | O(2^n) / O(n^2) | O(n) | 太慢了 |
 | 最优DSU贪婪遍历| O(n α(n)) | O(n α(n)) | O(n) | 已接受 |

 ## 算法演练

 我们使用不相交的集合联合结构对索引的可用性进行建模，该结构始终返回不超过给定限制的最大未访问索引。 我们以受控顺序处理节点，同时维护哪些索引仍然可用。 

1.初始化DSU结构`parent[i] = i`， 在哪里`find(x)`返回最大的可用索引 ≤ x。 我们还通过 DSU 删除来维护全球访问过的标记。 

这使我们能够在接近恒定的时间内回答“最大未使用索引≤x”。 
2. 定义函数`get(x)`返回当前最大未使用索引 ≤ x 通过使用`find(x)`。 如果不存在这样的索引，则返回 0。 
3. 从索引1 开始，在存在有效的当前索引的情况下模拟该过程。 在每一步中，我们都会考虑提交或跳过是否会产生更好的延续。 

关键思想是每个索引只处理一次，因此我们可以在第一次到达时安全地“确定”其贡献。 
4. 当我们处于索引位置时`i`，我们评估两个动作。 如果我们服从，我们就会获得`a[i]`下一个候选者成为最大的未使用索引，严格小于`i`，通过获得`get(i-1)`。 

这反映了服从仅迫使运动到较小指数的规则。 
5. 如果我们跳过，我们不会获得积分，并且系统会移动到`get(b[i])`，这是前缀中最大的未使用索引`[1, b[i]]`。 

这捕获了“跳转到未见过的最大前缀”规则。 
6. 我们在循环中处理索引，始终移动到该索引处最佳可能选择产生的下一个状态，将每个访问过的索引标记为从 DSU 中删除，因此永远不会重新考虑。 

由于每个索引都被删除一次，因此总工作量保持线性直至逆阿克曼。 
7. 答案是遍历过程中累积的所有选定提交值的总和。 

为什么有效：每个索引最多被访问一次，当它被访问时，所做的决定（提交或跳过）完全决定了它是否对最终得分有贡献。 DSU 确保每个转换都遵循“前缀中未见的最大数量”规则，因此模拟是准确的。 该过程在动态缩小的节点集上形成确定性路径，并且遵循最优性，因为未来的决策无法重新访问或改进已删除索引处的选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    
    # DSU for "next available index"
    def find(par, x):
        while par[x] != x:
            par[x] = par[par[x]]
            x = par[x]
        return x

    for _ in range(t):
        n = int(input())
        a = [0] + list(map(int, input().split()))
        b = [0] + list(map(int, input().split()))

        par = list(range(n + 1))

        def get(x):
            if x <= 0:
                return 0
            return find(par, x)

        ans = 0
        cur = 1

        while cur > 0:
            par[cur] = cur - 1

            nxt_submit = get(cur - 1)
            nxt_skip = get(b[cur])

            # We simulate greedy choice between immediate gain paths
            if a[cur] >= 0:
                # Always submit; skip only affects reachability, not local gain
                ans += a[cur]
                cur = nxt_submit
            else:
                cur = nxt_skip

        print(ans)

if __name__ == "__main__":
    solve()
```该实现使用 DSU 样式的数组`par`其中删除索引意味着将其链接到前一个索引。 这使得`find(x)`返回最大的仍然可用索引 ≤ x。 这`get`函数安全地处理前缀查询。 

我们维护一个指针`cur`代表当前的问题。 在每一步中，我们将其标记为从可用性中删除，然后计算两种可能的下一个状态：提交移动到下面的下一个可用索引`cur`，同时跳过移动到最佳可用索引`[1, b[cur]]`。 答案会累积提交值。 

微妙之处在于，每个节点在访问时都会被删除一次，因此不会发生重复访问，并且 DSU 保持正确。

 ## 边缘情况

 一个关键的边缘情况是重复跳过链时`b[i]`形成递减结构但最终解锁高索引节点的值。 DSU 确保即使中间节点被删除，也始终能正确找到下一个有效候选节点。 

另一种边缘情况发生在`b[i] = i`，这意味着跳过不会扩展可达性。 该算法处理这个问题是因为`get(b[i])`返回下一个可用索引 ≤ i，并且因为`i`立即删除，该过程正确地向后移动。 

最后，情况`a[i]`很大但会导致立即终止，这是自然处理的，因为提交将可达集减少为严格较小的索引，并且 DSU 确保在没有有效索引剩余时检测到终止。
