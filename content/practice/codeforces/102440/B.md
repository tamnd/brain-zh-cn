 ## 解决方案
 ## 问题理解

 我们从排列开始`p`的数字来自`1`到`n`。 我们可以删除任何元素，但剩余元素必须保持其原始顺序，因此每个可能的结果都是排列的子序列。 

对于选定的长度子序列`m`，它的美在于`m`减去其反转次数。 反转是一对剩余元素，其中较早的元素大于较晚的元素。 因此，我们保留的每一个元素都会给我们带来一点美感，而保留的元素之间的每一次倒置都会消除一点美感。 

任务是选择一个子序列，其最终值为`number of kept elements - number of inversions`尽可能大。 

界限`n <= 2 * 10^5`立即排除检查所有子序列的算法，因为有`2^n`其中。 即使是二次算法在这种规模下通常也太大了。 我们周围需要一些东西`O(n log n)`或者，在最坏的情况下，接近线性时间。 输入是排列的事实也很有用，因为每个值都是不同的，因此“增加”意味着严格增加，而不会对相等值产生任何歧义。 

如果错过了潜在的观察，有几种边缘情况可能会欺骗实现。 为了`n = 1`，唯一可能的子序列是`[1]`，所以答案是`1`。 假设至少存在一个反转的方法可能会错误地返回零。 

考虑```
4
1 2 3 4
```整个排列没有反转，所以它的美在于`4`。 因此答案是`4`。 如果实现在看到模式时不必要地删除元素，则可能会丢失最佳元素。 

现在考虑```
2
2 1
```保留两个元素即可给出长度`2`和一个反转，所以美丽是`1`。 只保留其中一个元素也能带来美感`1`。 因此答案是`1`。 仅返回原始长度的方法将错误地返回`2`。 

一个不太明显的情况是```
5
3 1 2 5 4
```整个序列有两次反转，所以它的美在于`5 - 2 = 3`。 递增子序列`[1, 2, 5]`有长度`3`而且没有反转，所以很美`3`。 这表明最佳答案不一定需要保留最大可能的元素数量。 

## 方法

 直接蛮力方法是考虑排列的每个子序列。 对于每个选定的子序列，我们计算其反转并计算其美丽度，然后保留最大值。 这是正确的，因为每个合法结果都由一个子序列表示。 

问题是子序列的数量。 有`2^n`选择，如果我们检查最多`n`元素来构建子序列，然后直到`n^2`对来计算其反转，简单的实现可以采取`O(2^n n^2)`时间。 即使单独枚举子序列也是不可能的`n = 2 * 10^5`。 

更结构化的尝试是对子序列使用动态规划，但反转项耦合了每对选定的元素。 选择一个元素会影响后面选择的许多元素的成本，因此简单的最长子序列递归并不能直接描述美感。 

关键的观察完全消除了这个困难。 

假设选定的子序列包含至少一个反转。 选择参与的任意元素`k`倒置。 如果我们删除该元素，子序列长度将精确减少`1`，而反转计数正好减少`k`。 

它的美丽因`(-1) - (-k) = k - 1`。 

如果`k >= 1`，删除元素永远不会降低美感。 什么时候`k > 1`，美丽确实增加了。 什么时候`k = 1`，美丽不变。 

我们可以重复删除属于反转的元素。 最终不存在反转，因此所得子序列是严格递增的。 在这个过程中，美丽从未减少。 

这意味着每个子序列都有一个递增的子序列，其美感至少与原始子序列的美感一样大。 递增子序列的反转为零，因此它的美妙之处在于它的长度。 

因此，最佳可能的美感正是原始排列的递增子序列的最大长度。 换句话说，这个问题相当于寻找LIS。 

标准`O(n log n)`LIS算法维护一个数组`tails`， 在哪里`tails[k]`是长度递增子序列的最小可能结束值`k + 1`到目前为止所看到的。 对于每个排列值，二分查找找到其值至少为当前值的第一个位置。 替换该值可以保留最大可能的未来潜力。 如果当前值大于每个存储的尾部，我们就扩展 LIS。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(2^n n^2)`|`O(n)`每个子序列| 太慢了|
 | 最佳 |`O(n log n)`|`O(n)`| 已接受 |

 ## 算法演练

 1.创建一个空数组`tails`。 它的长度将始终等于迄今为止找到的最长递增子序列的长度。 
2. 从左到右处理排列。 对于当前值`x`, 二分查找第一个位置`pos`在`tails`这样`tails[pos] >= x`。 
3. 如果存在这样的位置，则更换`tails[pos]`和`x`。 我们不改变所表示的子序列的长度，但我们获得了更小的最终值，这提供了更多机会用未来的元素扩展它。 
4. 如果不存在该职位，`x`比当前的每个尾部都大。 将其附加到`tails`，因为递增子序列现在可以扩展一个元素。 
5. 处理完所有值后，返回`len(tails)`。 通过上面的观察，这个LIS长度正是可以达到的最大美感。 

替换尾部是安全的原因是我们只关心每个子序列长度的最佳可能结束值。 假设两个递增子序列具有相同的长度，但其中一个以`4`另一个结尾是`7`。 子序列结束于`4`总是至少对于以后的扩展有用，因为可以遵循的每个未来值`7`也可以关注`4`。 因此，保持尽可能小的尾部是正确的状态压缩。 

### 为什么它有效

 考虑任何具有美感的子序列`B`。 如果包含反转，则选择至少参与一次反转的元素并将其删除。 如果该元素参与`k`反转，长度减少 1，反转计数减少`k`，所以美感会改变`k - 1 >= 0`。 重复这个过程至少会产生一个越来越美观的子序列`B`。 因此，没有哪个子序列比 LIS 的长度更美丽。 

相反，LIS 本身是递增的，因此它的反转为零。 它的美丽正是在于它的长度。 因此，LIS 长度既是可实现的美感，也是每种可能的美感的上限，使其成为准确的答案。 

## Python 解决方案```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    tails = []

    for x in p:
        pos = bisect_left(tails, x)

        if pos == len(tails):
            tails.append(x)
        else:
            tails[pos] = x

    print(len(tails))

if __name__ == "__main__":
    solve()
```使用读取输入`sys.stdin.readline`，这避免了不必要的开销`n`与`2 * 10^5`。 

这`tails`数组最初是空的。 对于每个值`x`,`bisect_left`查找包含大于或等于值的第一个位置`x`。 因为原始输入是排列，所以所有值都是不同的，但是`bisect_left`仍然是正确的选择，因为所需的子序列是严格递增的。 如果可能存在重复值，请使用`bisect_right`会错误地允许相等的值来扩展子序列。 

什么时候`pos`等于`len(tails)`,`x`比每个当前尾部都大，因此所表示的 LIS 可以扩展。 否则，更换`tails[pos]`和`x`保持相同的子序列长度，同时降低其结束值。 

Python 整数不会溢出，尽管答案最多是`n`反正。 二分查找还可以处理空的`tails`数组正确，所以`n = 1`不需要特殊情况。 

## 工作示例

 ### 示例 1

 输入是```
5
1 2 3 5 4
```该算法处理每个值并为每个增加的子序列长度维护尽可能小的尾部。 

| 当前值|`tails`加工后| LIS 长度 |
 | --- | --- | --- |
 |`1`|`[1]`|`1`|
 |`2`|`[1, 2]`|`2`|
 |`3`|`[1, 2, 3]`|`3`|
 |`5`|`[1, 2, 3, 5]`|`4`|
 |`4`|`[1, 2, 3, 4]`|`4`|

 什么时候`4`到达时，它无法扩展四个子序列的长度，因为`4 < 5`。 相反，它取代了`5`作为长度为四的递增子序列的尾部。 实际的子序列是`[1, 2, 3, 4]`，没有反转，因此具有美感`4`。 

答案是`4`。 

### 示例 2

 输入是```
6
2 1 3 4 5 6
```状态的演变如下。 

| 当前值|`tails`加工后| LIS 长度 |
 | --- | --- | --- |
 |`2`|`[2]`|`1`|
 |`1`|`[1]`|`1`|
 |`3`|`[1, 3]`|`2`|
 |`4`|`[1, 3, 4]`|`3`|
 |`5`|`[1, 3, 4, 5]`|`4`|
 |`6`|`[1, 3, 4, 5, 6]`|`5`|

 前两个元素不能同时属于严格递增子序列。 什么时候`1`到达，它取代`2`作为长度为 1 的子序列的最小可能尾部。 随后的值可以将该状态扩展到长度五。 

由此产生的 LIS 为`[1, 3, 4, 5, 6]`。 它的美在于`5`，匹配输出。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(n log n)`| 每个`n`值执行一次二分搜索`tails`。 |
 | 空间|`O(n)`|`tails`每个 LIS 长度最多包含一个值。 |

 和`n <= 2 * 10^5`,`O(n log n)`只需要几百万次二分搜索操作，这对于约束来说是合适的。 内存使用量是线性的并且完全在预期限制内。

## 边缘情况

 对于单元素输入```
1
1
```

`tails`开始为空。 价值`1`插入到位置零，产生`[1]`，答案是`1`。 没有反转来减去，所以唯一可能的美确实是`1`。 

对于递减排列```
2
2 1
```第一个价值创造`tails = [2]`。 价值`1`取代`2`, 给予`tails = [1]`。 LIS 长度为`1`。 原二元数列有一个倒置和美感`2 - 1 = 1`，同时删除任一元素也能带来美感`1`。 这证实了该算法并不假设保留更多元素总是能提高美观度。 

对于已经增加的排列```
4
1 2 3 4
```每个值都大于当前的最终尾部，所以`tails`长到`[1, 2, 3, 4]`。 答案是`4`。 由于没有反转，整个序列已经实现了这种美感。 

对于可以删除倒置而不失去美感的序列，请考虑```
5
3 1 2 5 4
```整个序列有两个反转，`(3,1)`,`(3,2)`，还有`(5,4)`，所以它的美丽实际上是`5 - 3 = 2`。 LIS 算法产生`tails`州`[3]`,`[1]`,`[1,2]`,`[1,2,5]`，最后`[1,2,4]`，给出长度的 LIS`3`。 子序列`[1,2,4]`没有反转和美感`3`，这绝对比保留所有内容要好。 这个案例说明了为什么在考虑反演之前不能将目标简化为最大化子序列长度。 

对于边界值`n = 2 * 10^5`，该算法仍然对每个输入值执行一次二分搜索。 尺寸为`tails`至多是`2 * 10^5`，因此每个操作都保持在`O(log n)`边界。 不使用递归，避免了递归深度问题，并且 Python 的整数表示足以满足答案。
