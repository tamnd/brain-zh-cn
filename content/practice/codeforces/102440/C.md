 ## 解决方案
 ## 问题理解

 我们正好得到了三个整数，我们可以对它们重新排序。 目标是打印订单`x y z`这样`x + y = z`。 如果没有排列具有此属性，我们打印`-1 -1 -1`。 接受任何有效的订单。 

输入值满足`-2^63 < a_i < 2^63`。 因此，这些数字可能接近有符号 64 位整数的限制，因此实现应避免假设值适合较小的整数类型。 Python 整数具有任意精度，因此算术如`a + b`即使数学和超出输入范围也是安全的。 

只有三个数字。 这使得搜索空间恒定：最多有六种排列，并且检查每一种排列都需要恒定的时间。 即使直接枚举所有排列也足够快。 问题的有趣部分不是性能，而是认识到只有三种可能的选择，其中数字充当`C`。 

一些边缘情况可能会导致粗心的实施失败。 首先，数字可以包含零。 用于输入`0 0 0`，正确的输出是`0 0 0`， 因为`0 + 0 = 0`。 将零视为特殊失败值的实现是错误的。 

重复值也是有效的。 用于输入`1 1 2`，输出`1 1 2`有效是因为`1 + 1 = 2`。 假设所有三个数字必须不同的解决方案将拒绝有效的情况。 

负值不需要特殊处理。 用于输入`-5 2 -3`，正确的输出是`-5 2 -3`， 自从`-5 + 2 = -3`。 只寻找正和会错误地拒绝它。 

最后，输入值可以接近 64 位边界。 例如，`9223372036854775807 -1 9223372036854775806`有有效的订单。 在比较之前执行溢出加法的固定宽度实现可能会产生不正确的结果，而 Python 会精确处理计算。 

## 方法

 最直接的方法是尝试这三个数字的所有可能的排序。 有`3! = 6`排列。 对于每个排列，我们检查前两个值是否加起来等于第三个值。 如果一种排列满足方程，我们立即打印它。 如果所有六个都失败，则不存在有效的排序。 

这种蛮力方法对于实际问题来说已经是最佳的。 最坏的情况正好执行六次检查，因此它的运行时间是`O(6)`，这就是简单的`O(1)`。 没有任何输入大小可以使六次检查变得太慢。 

我们可以通过观察唯一有意义的选择是三个数字中的哪一个来使恒定的工作量变得更小`C`。 如果`a`是`C`，另外两个必须是`b`和`c`，所以我们检查`b + c = a`。 同样，我们检查`a + c = b`和`a + b = c`。 这些正是三个可能的方程，每个成功的方程都会立即给出所需的排序。 

蛮力方法之所以有效，是因为排列空间很小。 结构观察使我们能够避免完全生成排列，从而将解决方案减少为三个算术比较。 两种方法都被接受，但直接三检查版本更简单，并且使推理特别透明。

 ## 算法演练

 1. 将三个整数读为`a`,`b`， 和`c`。 我们保留它们的原始顺序，因为可以直接检查右侧的三个可能选择中的每一个。 
2. 检查是否`a + b = c`。 如果为真，则打印`a b c`。 这里`c`是选择的右侧，而`a`和`b`是两个加数。 
3. 否则，检查是否`a + c = b`。 如果为真，则打印`a c b`。 这使用`b`作为右侧，并将其他两个值放在第一位。 
4. 否则，检查是否`b + c = a`。 如果为真，则打印`b c a`。 这是右侧最终可能的选择。 
5. 如果三个方程都不成立，则打印`-1 -1 -1`。 每个可能的排序都必须准确选择三个输入值之一作为第三个值，因此所有可能的情况现在都已穷尽。 

### 为什么它有效

 关键的不变量是每个有效的排序都必须指定一个输入数字作为右侧`C`。 如果`C`是`c`，所需方程为`a + b = c`。 如果`C`是`b`， 这是`a + c = b`。 如果`C`是`a`， 这是`b + c = a`。 该算法精确地检查这三种可能性，因此每当它打印有效的排序时，该排序就满足所需的方程。 如果三项检查全部失败，则别无选择`C`可以工作，这意味着没有排列可以成为解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b, c = map(int, input().split())

    if a + b == c:
        print(a, b, c)
    elif a + c == b:
        print(a, c, b)
    elif b + c == a:
        print(b, c, a)
    else:
        print(-1, -1, -1)

if __name__ == "__main__":
    solve()
```第一行`solve`准确读取三个输入整数。 没有可循环的测试用例，因为问题提供了一个三元组。 

第一个条件对应于第一个算法步骤并使用`c`结果。 第二个条件互换`b`和`c`在输出中因为`b`现在就是结果了。 第三个条件类似地`a`最后的。 

支票使用`elif`，因此一旦找到有效的排序，后面的情况就无法替代它。 这也可以正确处理重复值。 例如，与`0 0 0`，第一个条件成功，程序打印原始排序。 

Python 的任意精度整数在数值边界上非常有用。 输入值可以接近`2^63`，并且中间和可以超出有符号的 64 位范围，但 Python 计算总和时不会溢出。

        print(a, c, b)

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_input = input

    try:
        sys.stdin = io.StringIO(inp)
        input = sys.stdin.readline

        old_stdout = sys.stdout
        sys.stdout = io.StringIO()

 ## 边缘情况

 全零的情况`0 0 0`达到第一个条件，因为`0 + 0 = 0`。 算法打印`0 0 0`，因此重复值和零不需要特殊分支。 

对于重复的非零值，请考虑`1 1 2`。 第一个检查给出`1 + 1 = 2`，所以程序打印`1 1 2`。 两个输入位置包含相同值的事实不会改变算术或使排序无效。 

对于负值，请考虑`-5 2 -3`。 第一次检查成功是因为`-5 + 2 = -3`，程序打印`-5 2 -3`。 该算法从不假设操作数或结果为正。 

对于第一个输入值是总和的情况，请考虑`12 5 7`。 第一次检查测试`12 + 5 = 7`并失败了。 第二次测试`12 + 7 = 5`并失败了。 第三次测试`5 + 7 = 12`并成功，所以输出是`5 7 12`。 这证实了算法检查了右侧的所有三种可能的选择。 

在数值边界处，`9223372036854775807 -1 9223372036854775806`满足`9223372036854775807 + (-1) = 9223372036854775806`。 Python 对此进行了精确计算，因此边界值不会引入溢出或截断。 

最后，`2 4 42`练习失败路径。 三个可能的方程是`2 + 4 = 42`,`2 + 42 = 4`， 和`4 + 42 = 2`，全是假的。 由于第三个值的所有可能选择都已被拒绝，`-1 -1 -1`是唯一正确的反应。
