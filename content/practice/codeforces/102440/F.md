 ## 解决方案
 ## 问题理解

 我们有编号为 (1) 到 (n) 的朋友，并且朋友 (i) 为接收他们的三支队伍中的任意一支贡献了 (i) 的力量。 每个朋友必须恰好属于一个团队，并且三个团队的总和必须相等。 任务是打印这样的分区，或者报告不存在。 

总强度为

 [
 S = 1+2+\dots+n = \frac{n(n+1)}2。 
]

 如果存在有效分区，则每个团队都必须有实力

 [
 T = \frac{S}{3} = \frac{n(n+1)}6。 
]

 因此 (n(n+1)) 能被 (6) 整除是第一个必要条件。 然而，对于小(n)来说这还不够。 例如，(n=2)给出总实力(3)，因此目标是(1)，但只有朋友(1)可以组成实力(1)的团队。 同样，(n=3) 具有目标 (2)，但只有编号为 (2) 的单个朋友具有该强度。 

约束 (n\le 10^6) 使问题的建设性具有决定性。 我们可以承受所有（n）个玩家的传递，但是任何指数或二次的都完全超出范围。 官方竞赛版本对该问题给出了 1 秒的限制和 256 MB 的内存，因此预期的解决方案必须接近 (n) 中的线性。 

仅基于整除性的解决方案可能会错误处理几种小的边界情况。 对于(n=1)，总实力为(1)，因此不可能有三支正实力球队。 对于(n=2)，总数可以被3整除，但目标是(1)，并且只有一名实力为(1)的玩家，所以答案仍然是`Impossible`。 对于 (n=3)，目标是 (2)，并且同样只有一个子集具有该总和，即 ({2})。 输入 (n=4) 的总数为 (10)，它不能被 3 整除，所以它立即不可能。 第一个可能的值是 (n=5)，其中球队可以是 ({5})、({4,1}) 和 ({3,2})，实力均为 (5)。 

## 方法

 直接的暴力解决方案可以将每个玩家独立分配到三个团队之一。 有 (3^n) 个作业。 选择作业后，我们将计算三个总和并检查它们是否相等，每个作业需要 (O(n)) 工作。 因此，最坏情况的操作计数约为 (n3^n)。 即使对于（n=30），这也已经太大了，而实际极限达到（10^6）。 

子集搜索方法仅稍好一些。 我们可以选择一支球队作为具有所需总和的子集，然后尝试对剩余的球员进行划分，但枚举子集已经花费了 (2^n)。 玩家的实力恰好是连续的整数 (1,2,\dots,n)，这一事实为我们提供了比一般子集和实例更强的结构。 

关键的观察是查看六个连续的数字。 考虑块

 [
 L、L+1、L+2、L+3、L+4、L+5。 
]

 它总是可以分成三对

 [
 {L+5,L},\qquad
 {L+4,L+1},\qquad
 {L+3，L+2}。 
]

 每对都有和

 [
 2L+5。 
]

 因此，每个由六名连续球员组成的区块都可以添加到已经有效的解决方案中，而不会改变三支球队实力之间的平等。 这意味着我们只需要构建一些小的起始配置。 此后，每增加六名球员都将受到相同的处理。 

有用的基本配置特别小：

 [
 \开始{对齐}
 n=5 &: {5},{4,1},{3,2},\
 n=6 &: {6,1},{5,2},{4,3},\
 n=8 &: {8,4},{7,5},{6,3,2,1},\
 n=9 &: {9,6},{8,7},{5,4,3,2,1}。 
\结束{对齐}
 ]

 他们的团队总和分别为（5）、（7）、（12）和（15）。 

这四个基础涵盖了可以产生解决方案的所有可能的残留物类别。 如果(n\equiv 0\pmod 6)，则从(6)开始。 如果(n\equiv2\pmod6)，则从(8)开始。 如果(n\equiv3\pmod6)，则从(9)开始。 如果(n\equiv5\pmod6)，则从(5)开始。 (n) 的其余值有余数 (1) 或 (4)，因此它们的总强度不能被 3 整除。 

有两个特殊的小值（n=2）和（n=3），其中整除性成立，但不存在分区。 因此完整的条件是 (n\ge5) 和

 [
 n\bmod6\in{0,2,3,5}。 
]

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(n3^n)) | (O(n)) | (O(n)) | 太慢了|
 | 优化施工| (O(n)) | (O(n)) | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1. 计算 (n\bmod6)。 如果(n<5)，唯一需要特别注意的候选者是(1,2,3,4)，并且所有这些都是不可能的。 如果余数为(1)或(4)，则总强度不能被3整除，所以打印`Impossible`。 
2、根据残留量选择小碱。 对于残基 (5)，将 (1,\dots,5) 划分为 ({5})、({4,1}) 和 ({3,2})。 对于残基 (0)，请将 (1,\dots,6) 与 ({6,1})、({5,2}) 和 ({4,3}) 结合使用。 对于残基 (2)，将 (1,\dots,8) 与 ({8,4})、({7,5}) 和 ({6,3,2,1}) 结合使用。 对于残基 (3)，将 (1,\dots,9) 与 ({9,6})、({8,7}) 和 ({5,4,3,2,1}) 结合使用。 
3.让`left`是第一个不包含在基数中的数字。 以六人为一组处理剩余的玩家。 对于从 (L) 开始的区块，将 (L+5) 和 (L) 添加到第一队，将 (L+4) 和 (L+1) 添加到第二队，将 (L+3) 和 (L+2) 添加到第三队。 每支队伍恰好获得 (2L+5) 额外力量。 
4. 将 (L) 增加 6 并继续，直到分配完所有玩家。 因为基础大小与 (n) 具有相同的模六余数，所以剩余玩家数量始终是六的倍数。 
5. 打印`Possible`以及三支组建的队伍。 他们的总和相等，因为基本总和相等，并且每个添加的六人组为每支球队贡献相同的金额。 

### 为什么它有效

 不变量是，在处理完基地和任意数量的完整六人区块后，所有三支球队的总实力完全相同，并且每个处理过的球员都属于一支球队。 基数直接满足这个不变量。 对于后面的每个块，添加的三个对具有相同的总和 (2L+5)，因此添加块可以保持相等。 由于基础加上所有已处理的块最终包含从 (1) 到 (n) 的每个玩家，因此最终的团队形成一个完整的有效分区。 

对于不可能，当 (n\equiv1) 或 (4\pmod6) 时，(n(n+1)/2) 不能被三整除，因此不可能存在相等的团队总和。 其余5个以下的值单独检查，不承认三个相等的正强度团队。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    if n < 5 or n % 6 in (1, 4):
        print("Impossible")
        return

    r = n % 6

    if r == 5:
        teams = [
            [5],
            [4, 1],
            [3, 2],
        ]
        start = 6

    elif r == 0:
        teams = [
            [6, 1],
            [5, 2],
            [4, 3],
        ]
        start = 7

    elif r == 2:
        teams = [
            [8, 4],
            [7, 5],
            [6, 3, 2, 1],
        ]
        start = 9

    else:  # r == 3
        teams = [
            [9, 6],
            [8, 7],
            [5, 4, 3, 2, 1],
        ]
        start = 10

    left = start

    while left <= n:
        teams[0].extend([left + 5, left])
        teams[1].extend([left + 4, left + 1])
        teams[2].extend([left + 3, left + 2])
        left += 6

    out = ["Possible"]

    for team in teams:
        out.append(str(len(team)))
        out.append(" ".join(map(str, team)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```第一个条件处理整除失败和小的异常值。 检查`n < 5`在余数之前是方便的，因为 (n=2) 和 (n=3) 否则会通过整除性测试。 

四个基本情况是硬编码的，因为它们是构造中唯一真正特殊的部分。 它们的大小为 (5,6,8,9)，每个相应的残基保证`n - start + 1`能被六整除。 

该循环一次恰好处理六名新玩家。 第一队获得`left + 5`和`left`，第二个接收`left + 4`和`left + 1`，第三个接收到`left + 3`和`left + 2`。 所有三对总和为相同值，因此无需计算运行目标。 

Python 整数具有任意精度，因此从概念上计算和时不存在溢出问题。 实现时甚至不需要计算总强度，这也使得施工简单。 

输出将所有玩家编号存储在三个列表中。 由于每个玩家只出现一次且 (n\le10^6)，因此存储的数据总量为 (O(n))。 加入每个列表一次可以避免单独打印每个数字的开销。

 这三个总和都是 (7)，并且从 (1) 到 (6) 的每个玩家都恰好出现一次。 生成的输出与第一个示例的结构相同。

这两个示例还说明了为什么该解决方案不仅仅基于检查总数是否能被三整除。 该构造需要一个有效的小起始分区，之后由六人块不变量接管。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O(n)) | (O(n)) | 每个球员都被准确地插入一个球队，然后被写入一次。 |
 | 空间| (O(n)) | (O(n)) | 三个输出列表总共包含 (n) 个玩家编号。 |

 对于 (n\le10^6)，单次线性传递是合适的。 该构造仅为每组六个玩家执行恒定量的工作，并且输出本身已经包含 (n) 个数字，因此 (O(n)) 时间对于需要打印整个分区的问题来说是渐近最优的。

 ## 边缘情况

 对于 (n=1)，算法立即打印`Impossible`因为三个非负团队总和不可能全部相等 (1/3)。 无需构建任何东西。 

对于（n=2），总强度为（3），因此所需强度为（1）。 唯一可能具有实力 (1) 的团队是 ({1})，因此无法再创建两个具有实力 (1) 的团队。 这`n < 5`条件在残留检查可能错误地接受它之前捕获它。 

对于 (n=3)，总数为 (6)，给出目标强度 (2)。 总和为 (2) 的唯一子集是 ({2})，因此不能组成三个这样的团队。 同样的小值条件可以处理这种情况。 

对于 (n=4)，总数为 (10)，不能被 3 整除。 余数为 (4)，因此算法打印`Impossible`无需尝试构建。 

对于 (n=5)，特殊基为

 [
 {5},\quad{4,1},\quad{3,2}。 
]

 每个团队都有实力（5）。 这是尽可能小的有效输入，也解释了为什么残数 (5) 必须包含在有效案例列表中。 

对于 (n=8)，基数为

 [
 {8,4},\quad{7,5},\quad{6,3,2,1}。 
]

 每队都有实力（12）。 这个案例捕获了一个只知道如何构造六的倍数的实现。 

对于 (n=11)，算法从五人构建开始并处理块 (6,\dots,11)。 该块变成

 [
 {11,6},\quad{10,7},\quad{9,8},
 ]

 每对的总和为 (17)。 最初的队伍每队的总和为 (5)，因此最后三支队伍的总和为 (22)。 

对于 (n=10^6)，余数为 (4)，因此答案立即`Impossible`。 这很有用，因为最大输入并不总是意味着大输出。 该算法会在恒定时间内拒绝它，而不是不必要地分配一百万个元素的构造。
