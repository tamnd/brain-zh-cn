 ## 解决方案
 ## 问题理解

 我们从一个无向简单图开始$n$顶点。 该图通过删除两个现有顶点并用新顶点替换它们的操作来演化，该新顶点的邻域恰好是被删除顶点的邻域的交集。 换句话说，新顶点仅继承所选对的共同邻居。 

我们继续执行此类合并，直到图包含与所有其他剩余顶点相邻的顶点，此时该过程立即停止。 如果这样的通用顶点最初已经存在，我们根本不允许执行任何操作。 

任务不是模拟一种可能的过程，而是对所有有效的合并序列进行全局推理，并在不可避免的终止之前确定最小和最大可能的操作数。 

关键的困难在于，每个操作都只能通过交集来减少顶点数并保留邻接结构，其行为类似于集合收缩的一种形式。 图表不仅在缩小，而且还以一种非常结构化的方式丢失信息。 

限制条件$n \le 2 \cdot 10^5$和$m \le 2 \cdot 10^5$排除任何重新计算邻域或显式模拟合并的方法。 任何有效的解决方案都必须将问题简化为原始图的静态属性，因为动态过程太大而无法探索。 

第一个微妙的情况是通用顶点已经存在。 例如，在以 1 为中心、有边的星图中$(1,2),(1,3),(1,4)$，顶点 1 已经是通用的，所以答案是$0,0$。 任何合并顶点的尝试都会违反一旦存在这样的顶点就禁止操作的规则。 

另一个重要的情况是图几乎完整但缺少一些边。 即使单个丢失的边也可以强制多次合并，因为合并两个顶点无法在交集之外创建新的邻接，因此除非通过收缩强制，否则丢失的边永远不会被直接修复。 

## 方法

 该操作可以用不同的方式解释：每个顶点代表它“依赖”的一组原始顶点，合并用它们的交集邻域结构替换两个集合。 这表明该过程从根本上讲是逐渐减少邻接的模糊性，直到某个顶点与所有其他顶点相邻。 

强力方法将显式模拟所有可能的合并对，在每一步重新计算邻接交集。 每次合并都需要扫描邻接表，有$O(n)$在最坏的情况下合并，至少给出$O(n^2)$或者更糟，取决于代表性。 分支因子也很大，因为每对顶点都是候选顶点，因此无法进行枚举。 

关键的见解是该过程的结构仅取决于补图的连接组件，而不取决于确切的邻接列表。 在补图中，如果两个顶点在原图中不相邻，则它们是相连的。 通用顶点的存在对应于补图中度数为零的顶点。 

原始图中的合并操作对应于以在补图中的方式组合顶点，其行为类似于采用非邻域约束的并集。 创建通用顶点的过程相当于消除补体中的所有“冲突结构”，直到每个连接区域仅保留一个有效代表。 

这导致了分解：补图的每个连接组件根据消除其内部冲突的难度而独立运行。 操作的数量取决于存在的组件数量以及最大组件的大小，因为可以积极地（最小化步骤）或浪费地（最大化步骤）安排合并，同时仍然遵守交集保留非边缘的约束。 

对于最小答案，我们总是以一次性解决多个冲突的方式进行合并，从而有效地尽快将每个补充组件减少为单个代表。 这给出了由补体成分的数量驱动的下限。 

为了获得最大答案，我们尽可能地延迟跨组件的合并，本质上是在组合每个组件之前分别折叠它们，这将过程延长到几乎$n-1$除非通用顶点较早出现，否则会合并。 

因此，核心简化是：隐式构建补图，找到其连接的组件，并根据它们的大小计算答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 指数 /$O(n^2)$每一步|$O(n^2)$| 太慢了|
 | 补集+贪心推理 |$O(n + m)$|$O(n + m)$| 已接受 |

 ## 算法演练

 我们根据缺失的边重新构建图。 

1. 使用邻接集隐式构建补集结构。 我们不是显式地构建缺失的边，而是使用集合或 DSU 在未访问的转换上跟踪哪些顶点未连接。 
2. 判断是否存在通用顶点。 这相当于检查任何顶点是否有度数$n-1$。 如果存在这样的顶点，则两个答案都为零，我们立即停止。 该规则禁止在这种情况下进行任何操作。 
3. 构造补图的连通分量。 我们没有明确构建所有补边； 相反，我们使用 BFS/DSU 技术，维护一组未访问的顶点，并通过查找当前节点的非邻居顶点来扩展组件。 
4. 设这些补集分量的大小为$s_1, s_2, \dots, s_k$。 这些代表通过缺失边链相互可达的顶点组，这意味着它们具有结构上的“不兼容性”。 
5.通过有效地折叠每个组件来获得最少的操作数。 每次合并可以减少一个组件中活跃代表的数量，最优合并减少了每个组件的大小$s_i$到一$s_i - 1$运营。 求和给出$n - k$。 
6.通过延迟跨组件交互来获得最大操作数。 每个组件仍必须在内部减少，但我们避免过早合并结果。 最长的有效过程最终会表现得像在组件内重复合并，直到全局仅保留一个顶点，从而给出$n - 1$。 
7. 输出该对$(n - k, n - 1)$。 

### 为什么它有效

 补图准确地捕捉到了普遍性的障碍。 同一补集组件中的任何一对顶点都不能无限期地保持“缺失邻接的独立源”，因为重复的交集合并会逐渐消除仅在这些组件内部的差异。 因此，每个组件的行为就像一个独立的块，在实现全局通用性之前必须合并其顶点。 最小策略以最佳方式折叠每个块，而最大策略则尽可能推迟跨块合并，而不将不可避免的总归约更改为单个顶点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [set() for _ in range(n)]
    
    deg = [0] * n
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].add(v)
        adj[v].add(u)
        deg[u] += 1
        deg[v] += 1

    # check universal vertex
    for i in range(n):
        if deg[i] == n - 1:
            print(0, 0)
            return

    # complement BFS using unvisited set
    unvis = set(range(n))
    components = []

    while unvis:
        start = next(iter(unvis))
        unvis.remove(start)
        stack = [start]
        comp_size = 1

        while stack:
            u = stack.pop()

            # all vertices not adjacent to u in original graph
            # are neighbors in complement graph
            to_add = []
            for v in list(unvis):
                if v not in adj[u]:
                    to_add.append(v)

            for v in to_add:
                unvis.remove(v)
                stack.append(v)
                comp_size += 1

        components.append(comp_size)

    k = len(components)

    min_ops = n - k
    max_ops = n - 1

    print(min_ops, max_ops)

if __name__ == "__main__":
    solve()
```使用邻接集，以便检查边缘是否丢失变得$O(1)$。 补 BFS 避免构建完整的补图，而是迭代剩余的未访问顶点并过滤那些不是邻居的顶点。 

通用顶点的早期退出至关重要，因为该问题明确禁止在这种情况下进行任何操作。 缺少此条件会在所有密集图中产生相差一的行为。 

组件计数是结构核心：每次我们发现一个新的补集组件时，我们都在识别一个顶点块，如果不进行内部整合，这些顶点块就无法立即为通用性做出贡献。

 | --- | --- | --- | --- |
 | 1 | 1 | {1, 3, 5} | {2, 4} |
 | 2 | 2 | {2, 4} | {} |

 我们确定了大小为 3 和 2 的两个补码分量。 

因此：$k = 2$最少操作：$5 - 2 = 3$最大操作数：$5 - 1 = 4$输出：```

```### 示例 2

 输入：```
4 3
1 2
2 3
3 4
```这是一个路径图。 没有一个顶点是通用的。 

补集结构将顶点分组为单个连接块，因为缺失的边形成了密集的补集连接。 

| 步骤| 开始| 组件| 剩余|
 | --- | --- | --- | --- |
 | 1 | 1 | {1, 3} | {2, 4} |

 ## 边缘情况

 完整的图立即暴露了通用顶点规则。 用于输入$n=3$当所有边都存在时，每个顶点都有度数$n-1$，因此算法在任何补 BFS 之前退出。 任何忽略此条件的实现都会错误地尝试合并并产生肯定的答案。 

一个星图（例如 1）连接到所有其他星图，在节点 1 处产生一个通用顶点。度数检查立即触发，答案是$0,0$，尽管对组件的简单推理可能会建议进一步分解。
