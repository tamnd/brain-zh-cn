 ## 解决方案
 ## 问题理解

 我们正在处理一棵树，其中每个顶点开始时都是未着色的。 在一次操作中，我们选择任意两个顶点，可能是同一个顶点两次，然后我们“重新着色”它们之间唯一路径上的每个顶点。 每次移动都会引入一个新的颜色索引，因此第一个操作用颜色 1 绘制路径，第二个操作用颜色 2 绘制路径，依此类推。 由于后面的操作会覆盖前面的操作，因此每个顶点的最终颜色只是所选路径覆盖它的最后一个操作。 

如果每个顶点都已被至少一次操作绘制，则着色被认为是完整的。 关键的数量不仅仅是保证覆盖，而是尽量减少需要多少次路径操作，然后统计所有最优策略中可以出现多少种不同的最终颜色分配。

 约束 n ≤ 32 是中心信号。 任何尝试枚举顶点子集、分区或操作序列的方法如果运行时间大致为 O(2^n) 或 O(3^n)，则可能是可行的，但任何接近阶乘增长的方法都会立即被排除。 这也强烈表明最优解决方案的结构取决于树的全局分区而不是逐步的贪婪构造。 

当树已经是简单路径时，就会出现微妙的边缘情况。 在这种情况下，以端点作为路径末端的单个操作对所有内容进行着色，只产生一种颜色。 另一个边缘情况是星形：选取两片叶子会强制一条路径穿过中心，但重叠操作可能会以不平凡的方式覆盖颜色，这意味着不同的最佳序列仍可能导致不同的最终顶点颜色。 

最危险的误解是独立地覆盖顶点来思考。 例如，在“T”形树中，尝试用中心重叠的路径分别覆盖每个分支会导致计数过多或错误的极小推理，因为单个路径可以根据端点同时覆盖多个分支。 

## 方法

 强力解释是考虑操作序列，其中每个操作选择一对顶点并绘制它们的路径。 由于最佳解决方案中有 O(n^2) 个可能的对，并且可能有多达 n 个操作，因此这会导致状态空间大得天文数字。 即使限制最小长度序列，分支因子仍然太大，并且不同的序列可能会折叠成相同的最终颜色，从而使简单的枚举变得浪费。 

关键的观察结果是，顶点的最终颜色仅取决于路径经过该顶点的最后一个操作。 这意味着每个顶点都被准确地分配给一个“最后负责路径”，并且这些路径形成一个结构，其中每个操作对应于由简单路径引起的顶点的连接子集。 关键的结构事实是，在最佳解决方案中，每个操作实际上对应于在树的某种收缩表示内选择一对叶子，并且操作的数量与消除所有分支歧义所需的“独立路径覆盖”紧密相关。 

这个问题简化为一个经典的观点：我们将树分解为一系列路径，使得每个顶点都被覆盖，并且每个操作对应于一条路径，但顺序仅取决于每个顶点上的最后一条路径。 最少的操作数就是某个归纳结构中最小路径覆盖的大小，并且由于我们在一棵树中，这相当于通过以最小化剩余分支的方式重复配对叶子来减少树。

因为 n 非常小，所以我们可以根据顶点子集的状态来思考，我们直接模拟构建最终的“最后颜色分配”。 每个顶点都被分配了覆盖它的最后一个操作的索引，可行性简化为检查共享相同标签的顶点是否可以被单个简单路径覆盖。 

因此，最佳方法成为位掩码上的子集 DP，其中我们尝试将顶点划分为组，每个组形成一条有效路径，并且我们计算有多少种方法来选择具有最少组数的划分。 树结构允许我们通过检查子集是否连通以及在导出子图中最多有两个度为 1 的顶点来有效地测试子集是否形成简单路径。 

我们逐步构建分区并跟踪最小部件数量和实现它的方法数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解操作序列 | 指数（有效超指数）| O(n) | 太慢了|
 | 将顶点分区上的 DP 子集化为路径 | O(n·2^n + 转换) | O(2^n) | O(2^n) | 已接受 |

 ## 算法演练

 我们将问题重新定义为将顶点集划分为组，其中每个组对应于单个操作最后绘制的顶点集。 每个这样的组都必须是树中的一条简单路径。 

1. 预先计算所有有效路径子集。 对于每对顶点 u 和 v，计算它们之间唯一路径上的顶点集。 这给出了 O(n^2) 候选子集。 我们将它们存储为位掩码。 
2. 构建布尔数组`is_path[mask]`在所有顶点子集上，最初为 false，并将与有效 u-v 路径相对应的每个掩码标记为 true。 这确保我们只考虑可以作为单个操作出现的子集。 
3. 定义子集上的DP。 让`dp[mask]`存储精确覆盖顶点所需的最小路径操作数`mask`作为不相交的有效路径组。 我们初始化`dp[0] = 0`和所有其他状态为无穷大。 
4.对于每个掩码，我们尝试通过选择子掩码来扩展它`sub`这是一条有效路径，并且完全包含在其余顶点中。 我们从`mask`到`mask | sub`，将操作数增加 1。这样做的原因是每个操作只贡献一个路径组，并且所选路径的并集必须覆盖所有顶点。 
5. 除了 DP 之外，维护第二个数组`ways[mask]`计算实现了多少个最佳结构`dp[mask]`。 当多种方式达到相同的最小值时，我们将它们对 998244353 求模求和。 
6.答案是`dp[full_mask]`和`ways[full_mask]`。 

正确性取决于以下事实：在任何最佳解决方案中，每个操作都贡献一组恰好是简单路径的顶点，并且这些集合形成树的不相交分区。 颜色的覆盖行为意味着每个顶点只有最后一个操作很重要，因此我们总是可以将最佳序列重新解释为不相交的最后绘制路径集的分区。 

### 为什么它有效

 每个有效的最终着色都会通过最后的操作产生顶点分区。 每个部分必须是一条连接路径，因为一次操作中绘制的所有顶点都位于一条简单路径上。 相反，可以通过适当地对这些路径进行排序来实现将顶点集划分为有效路径子集，因为后面的操作会覆盖前面的操作而不会破坏有效性。 因此，最小化操作相当于最小化此类分区中的路径子集的数量，并且对解决方案进行计数减少到对最小尺寸分区进行计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

n = int(input())
adj = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].append(v)
    adj[v].append(u)

# precompute parent and path masks using BFS from each node
from collections import deque

path_masks = []

def get_path(u, v):
    # BFS parent reconstruction
    parent = [-1] * n
    q = deque([u])
    parent[u] = u
    while q:
        x = q.popleft()
        if x == v:
            break
        for y in adj[x]:
            if parent[y] == -1:
                parent[y] = x
                q.append(y)
    # reconstruct
    mask = 0
    cur = v
    while True:
        mask |= (1 << cur)
        if cur == parent[cur]:
            break
        cur = parent[cur]
    return mask

for i in range(n):
    for j in range(i, n):
        path_masks.append(get_path(i, j))

# mark valid path subsets
is_path = [False] * (1 << n)
for m in path_masks:
    is_path[m] = True

INF = 10**18
dp = [INF] * (1 << n)
ways = [0] * (1 << n)

dp[0] = 0
ways[0] = 1

for mask in range(1 << n):
    if dp[mask] == INF:
        continue
    sub = (~mask) & ((1 << n) - 1)
    t = sub
    while t:
        low = t & -t
        i = (low.bit_length() - 1)
        # try all submasks of sub but we only consider valid path masks
        # iterate over all precomputed paths instead for simplicity
        t -= low

    # instead directly try all path masks
    for pm in path_masks:
        if pm & mask:
            continue
        nm = mask | pm
        nd = dp[mask] + 1
        if nd < dp[nm]:
            dp[nm] = nd
            ways[nm] = ways[mask]
        elif nd == dp[nm]:
            ways[nm] = (ways[nm] + ways[mask]) % MOD

full = (1 << n) - 1
print(dp[full], ways[full] % MOD)
```该代码构建所有简单路径顶点集，然后在位掩码上执行子集 DP。 基于 BFS 的路径重建可确保我们正确识别任意一对顶点之间的唯一路径。 

一个微妙的实现问题是 DP 必须迭代每个状态的所有路径子集，而不是尝试动态生成子掩码，因为约束 n ≤ 32 使得 O(n^2) 路径的预计算可行，但如果操作不当，2^n 状态的子掩码枚举将太慢。 

这`ways`仅当找到严格最优或同等最优的转换时才更新数组，确保模算术下的正确计数。 

## 工作示例

 ### 示例 1

 输入树：1-2-3

 我们列出了所有有效的路径掩码：{1}、{2}、{3}、{1,2}、{2,3}、{1,2,3}。 完整集合{1,2,3}本身就是一条路径，因此DP立即找到覆盖所有顶点的单个操作。 

| 面膜| DP | 使用的过渡| 解释|
 | --- | --- | --- | --- |
 | 000 | 000 0 | 开始 | 空集|
 | 111 | 111 1 | {1,2,3} | 一条路涵盖所有|

 DP 发现一次操作就足够了，并且不存在替代的最小分区，因此答案是 (1, 1)。 

### 示例 2

 考虑一颗星，其中心 1 连接到 2、3、4。 

有效路径子集包括所有边 {1,2}、{1,3}、{1,4} 和单边。 任何完全覆盖都需要至少两次操作，因为没有一条路径可以包含两个以上的叶子而不破坏路径结构。 

最小分区使用两个路径，例如 {2,1,3} 和 {4}。 

| 步骤| 选择的道路| 覆盖套装|
 | --- | --- | --- |
 | 1 | {2,1,3} | 1,2,3 |
 | 2 | {4} | 1,2,3,4 |

 这表明最佳解决方案不是唯一的，因为存在将叶子与中心配对的多种选择。

 ## 边缘情况

 线性链被正确处理，因为端点 (1, n) 之间的 BFS 生成等于完整顶点集的掩码，立即给出 dp[full] = 1。 

星形树迫使 DP 组合多条不相交的路径，算法正确地避免了非简单路径的非法子集，确保最小操作次数至少为 2。然后计数组件在每次操作中枚举不同的方式来选择哪些叶子与中心分组，从而产生多个最佳着色。
