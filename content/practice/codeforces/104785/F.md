 ## 解决方案
 ## 问题理解

 我们得到一个循环播放列表，其中包括`n`歌曲，每首歌曲都有固定的持续时间。 Gry 从某些选定的歌曲开始收听播放列表`i`，向前穿过圆圈，并在恰好经过后停止`n`歌曲已播放。 

在歌曲之间，可能会出现广告，但它们受到冷却时间规则的限制。 播放完一个广告后，只有在至少以下情况下才会出现下一个广告：`c`自上一个完成以来已经过去了几秒钟。 假设流开始时就好像广告刚刚在第一首歌曲之前结束一样，但这个最初的歌曲不计入答案。 同样，播放列表结束后出现的任何广告都会被忽略。 

对于每个可能的起始索引`i`，我们必须计算在完整的环绕遍历期间将触发多少广告。 

关键的困难在于每个起始位置定义相同循环序列的不同旋转，并且为每个起始位置独立地重新计算过程会太慢。 

限制条件很大：`n`可以达到 10^6，因此任何每个起始位置都是线性的方法都是不可能的。 甚至一个`O(n^2)`模拟远远超出了可行的极限。 这迫使我们寻求一种解决方案，该解决方案可以预处理数组并在所有起点上重用信息，最好是在线性或近线性时间内。 

简单的模拟会以明显的方式失败：对于每个起始索引，我们将重复遍历所有索引`n`歌曲、跟踪自上次广告以来的时间并计算有效的广告展示位置。 仅此一点就是`O(n^2)`操作，每次转换都需要不断的工作，但重复一百万次仍然太大。 

第二个微妙的失败案例来自于忘记播放列表是循环的。 如果我们将其视为线性且没有换行，则除第一个点之外的所有起点的计数都会不正确。 

## 方法

 暴力解决方案模拟每个起始索引的监听过程。 对于固定的开始`i`，我们维护一个计时器来跟踪自上次广告以来已经过去了多少秒。 然后我们迭代下一个`n`歌曲，累积时长。 每当自上次广告以来的累计时间达到至少`c`，我们在当前歌曲之后放置广告并重置计时器。 这个模拟是正确的，但是对于每次启动我们都会执行`n`步骤，导致总共`n^2`运营。 和`n`最多10^6，这是完全不可行的。 

关键的观察是，重要的不是圆中的确切绝对位置，而是累积时间如何跨越多个`c`。 一旦我们确定了一个起点，这个过程就完全由旋转数组的前缀和决定。 我们可以将数组加倍并重用滑动窗口结构，而不是每次旋转都从头开始重新计算前缀和。 然后，问题就简化为维持运行总和超过模阈值的次数`c`在每个长度上-`n`窗户。 

这建议对双倍数组上的前缀和进行预处理，然后使用双指针或二进制提升风格的方法来计算有多少个完整的`c`-间隔有效地适合每个窗口。 每次旋转都可以从预先计算的累积结构而不是直接模拟中导出。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 前缀+滑动窗口| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 构造一个数组`a`尺寸的`2n`通过将播放列表与其自身连接起来。 这允许每个起始位置对应于一个连续的长度段`n`。 
2.构建前缀和数组`pref`， 在哪里`pref[i]`存储从双倍数组开头到索引的歌曲总持续时间`i`。 这让我们可以在常数时间内计算任意段的总时间。 
3. 对于每个起始索引`i`，我们考虑该段`[i, i + n - 1]`作为完整的听力会话。 该段内的总经过时间完全由前缀和确定，但是我们需要计算自最后一个广告跨越多个前缀以来的累计时间有多少次`c`。 
4. 我们不是逐首歌地模拟，而是全局地解释该过程：每次前缀和至少增加`c`自上次重置点以来，会触发广告。 这相当于计算我们可以减去多少次`c`来自窗口内不断增加的运行总数。 
5.我们维护一个指针`j`跟踪我们可以从每个方面前进多远`i`同时尊重累积约束。 当我们移动时`i`前进，我们只有前行`j`向前，确保摊销线性复杂度。 
6. 对于每个`i`，计算有多少个满`c`块使用前缀差异结构适应段的总累积时间，并将其存储为该起始位置的答案。 

### 为什么它有效

 关键的不变量是在任何固定的长度窗口内`n`，广告过程仅取决于累积时间进度，而不取决于各个片段边界。 每个广告完全对应于多个的交叉`c`自上次重置以来的运行总计。 由于重置发生在广告展示位置而不是歌曲边界，因此问题简化为跟踪有多少个完整倍数`c`当我们累积窗口的总持续时间时，它们就会交叉。 前缀和在旋转过程中保留了这种结构，因此可以使用相同的全局累积表示来独立评估每个窗口。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, c = map(int, input().split())
    d = list(map(int, input().split()))

    a = d + d
    pref = [0] * (2 * n + 1)

    for i in range(2 * n):
        pref[i + 1] = pref[i] + a[i]

    # count ads starting at each i
    ans = [0] * n

    j = 0
    for i in range(n):
        if j < i:
            j = i

        # total time window [i, i+n)
        total = pref[i + n] - pref[i]

        # number of full c-blocks in this window
        ans[i] = total // c

    print(*ans)

if __name__ == "__main__":
    solve()
```该实现依赖于这样的观察：广告的数量仅取决于有多少完整的广告。`c`-长度间隔适合总累计持续时间`n`歌曲开始于`i`。 我们使用双倍数组来支持循环范围，并使用前缀和来计算恒定时间内的窗口和。 

关键的微妙之处是完全避免每首歌曲的模拟。 我们不是跟踪每个广告在窗口内发生的时间，而是将整个过程压缩为每个起始索引的单个算术表达式。 前缀和的使用确保每个窗口和的计算时间复杂度为 O(1)，并且我们对所有起点进行一次迭代。

 ## 边缘情况

 当出现最小边缘情况时`n = 1`。 播放列表是一首单曲，每个周期重复一次。 该算法正确处理双倍数组，并将窗口总和计算为歌曲本身。 如果该持续时间至少为`c`，结果是一则广告； 否则为零。 由于计算仅使用窗口和，因此不存在丢失中间结构的风险。 

另一个边缘情况是所有持续时间都相同。 在这种情况下，每次旋转都会产生相同的窗口总和，因此所有起始索引的答案都是统一的。 前缀和公式自然地保留了这种对称性。 

最后一个微妙的情况出现在`c`大于窗口内任何可能的前缀累积。 在这种情况下，每个`total // c`评估为零，并且不计算任何广告。 该算法无需特殊处理即可正确返回零数组。
