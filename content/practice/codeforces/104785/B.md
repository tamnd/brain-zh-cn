 ## 解决方案
 ## 问题理解

 我们正在模拟一个点击输入点击输出的交通系统，其中每位乘客都使用一张编号的旅行卡。 每个事件都会记录一个码头和一个卡ID，并且事件按时间顺序到达。 每张卡的行为都是独立的，我们必须在处理完所有事件后计算每张卡累积的总费用。 

行程是通过将同一张卡的两个连续事件配对而形成的：第一个事件是开始（点击进入），同一张卡的下一个事件是结束（点击退出）。 成本取决于这两个码头的关系。 如果起始码头和终止码头不同，则成本为其指数的绝对差。 如果它们是同一个码头，或者如果一张卡开始了一次旅行但从未结束它，则费用为 100 的固定罚款。 

主要的挑战是事件在许多卡上交错，因此每张卡都保持自己的“当前开放行程”状态。 我们需要处理多达 100000 个事件，因此任何尝试全局扫描或匹配的方法都会太慢。 我们必须维护每张卡的状态并在每个事件的恒定时间内更新答案。 

当卡末尾有不匹配的接入时，就会出现微妙的故障情况。 例如，如果一张卡片有一个事件`(pier 3, card 7)`并且没有进一步的事件，正确的成本是 100。仅对完整对进行收费的简单解决方案将错误地输出 0。另一个极端情况是重复点击而不在全局强制执行交替。 例如，一张卡可以在 1 号码头进站，在 2 号码头出站，然后在 2 号码头再次进站，在 2 号码头出站。最后一次旅行仍然要花费 100 美元，尽管它“看起来”是零距离移动，因为同一码头的旅行总是会受到处罚。 

这些约束意味着我们需要 O(1) 处理每个事件。 对于多达 100000 个事件，即使 O(k log k) 也是可以接受的，但没有必要。 n 的小界限（桥墩数量最多 50 个）与复杂性无关，仅定义距离的坐标空间。 

## 方法

 强力解释是存储每张卡的所有事件，并在每次发生抽头时重复向后扫描以查找先前不匹配的抽头。 这在逻辑上是有效的，因为每次行程都是通过配对两个事件来定义的，但如果简单地实现，它就会变得低效：每个事件都可能触发对该卡的所有先前事件的扫描，在最坏的情况下，当所有事件都属于一张卡并在打开和关闭之间交替时，会导致 O(k^2)。 

关键的观察是，每张卡只需要记住一个状态：当前是否有开放的行程，如果有，则起始码头。 一旦发生分流，我们立即解决成本并清除状态。 如果在没有开放行程的情况下发生新的接入，我们只需将其存储即可。 

这将问题简化为通过事件流的单次传递，为活动行程维护一个大小为 m 的字典或数组，并为累积成本维护另一个数组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（扫描每个事件的历史记录）| O(k²) | O(k) | 太慢了|
 | 最佳（每张卡的状态）| O(k) | O(米) | 已接受 |

 ## 算法演练

 我们维护两个按卡 ID 索引的数组。 一个存储每张卡当前开放的码头，另一个存储累计成本。 

1.初始化一个数组`open_pier`大小为 m，带有表示“无活动行程”的哨兵值，以及一个数组`cost`大小为 m 且用零填充。 哨兵确保我们能够明确区分活动和非活动状态。 
2. 处理每个事件`(p, c)`为了。 时间顺序保证每张卡必须按顺序进行配对。 
3.如果卡`c`没有活跃行程，商店`p`在`open_pier[c]`。 这代表着一次旅行的开始。 由于行程尚未完成，因此尚未产生任何费用。 
4.如果卡`c`已经有一个活跃的旅行开始于`open_pier[c]`，计算行程成本如下。 如果`p == open_pier[c]`, 加 100`cost[c]`。 否则添加`abs(p - open_pier[c])`。 
5. 处理完成行程后，重置`open_pier[c]`返回哨兵值，表明该卡已准备好进行新的旅行。 
6. 处理完所有事件后，任何仍具有非哨兵的卡`open_pier`值代表不完整的行程。 对于每张这样的卡，其成本增加 100。 

步骤 6 背后的原因是，系统将不完整的旅程定义为始终受到惩罚，无论它们从哪里开始。 

### 为什么它有效

 每张卡片的事件序列自然地分为不相交的连续对（开始，结束），除了可能的尾随开始。 该算法按到达顺序贪婪地强制执行此配对，这与系统的唯一有效解释相匹配。 由于一张卡不能有重叠的行程，因此仅存储一个活动开始状态就足以完全表示其当前上下文。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    
    open_pier = [-1] * (m + 1)
    cost = [0] * (m + 1)
    
    for _ in range(k):
        p, c = map(int, input().split())
        
        if open_pier[c] == -1:
            open_pier[c] = p
        else:
            start = open_pier[c]
            if p == start:
                cost[c] += 100
            else:
                cost[c] += abs(p - start)
            open_pier[c] = -1
    
    for c in range(1, m + 1):
        if open_pier[c] != -1:
            cost[c] += 100
    
    print(*cost[1:])

if __name__ == "__main__":
    solve()
```该解决方案使用两个按卡 ID 索引的数组。`open_pier`跟踪卡当前是否有未完成的旅程并存储其起始码头。 当该卡的第二个事件到达时，我们立即计算成本并重置状态。 处理完所有事件后，我们会执行最后一次清理，以对所有未完成的行程进行收费。 

一个常见的实施错误是忘记最后的扫描，这会导致从不使用的卡收费不足。 另一个微妙的问题是过早或过晚错误地重置状态； 计算成本后必须立即进行重置，以确保下一个事件被视为新的行程。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(k) | 每个事件都会处理一次，更新时间为 O(1) |
 | 空间| O(米) | 我们存储每张卡的一种状态和一种成本 |

 这些约束允许最多 100000 个事件和卡片，因此线性处理很容易在限制范围内。 内存使用量很小，因为我们只保留两个大小为 m 的数组。

 ## 边缘情况

 一种边缘情况是一张永远不会弹出的卡。 例如，输入：```
2 1 1
1 1
```该算法存储`open_pier[1] = 1`。 处理完所有事件后，最后的扫描加 100，产生输出`100`。 如果没有此步骤，结果将错误地保持为 0，因为没有形成完整的对。 

另一种情况是重复同码头行程。 例如：```
2 1 2
1 1
1 1
```第一个活动开启了一次旅行。 第二个事件在同一码头关闭它，触发固定惩罚 100。重置可确保如果发生另一个事件，它将开始新的行程，而不是错误地与过去的状态合并。 

最后一个微妙的情况是交错放置多张卡片：```
3 2 4
1 1
2 2
3 1
3 2
```卡 1 构成从 1 到 3 的行程，成本为 2。 卡 2 构成从 2 到 3 的行程，成本为 1。`open_pier`每张卡确保各州之间不会交叉污染。
