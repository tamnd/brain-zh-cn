 ## 解决方案
 ## 问题理解

 我们得到一个有向图，其中每个任务都是一个顶点，每个依赖项都是一个有向边。 一个边缘`a -> b`意味着任务`a`必须在任务之前执行`b`。 

问题是这些依赖关系可能包含定向循环，这使得不可能以有效的顺序执行所有任务。 我们可以删除一些边来消除所有环，但我们仍然必须保留至少一半的原始边。 

输出不是任务的排序，而是依赖边的子集，使得剩余的有向图没有有向循环，并且保留的边的数量至少是原始数量的一半。 

关键的结构要求是保留的边必须形成有向无环图。 这意味着必须存在某种顶点排序，使得每个保留的边都从较早的顶点到较晚的顶点。 

约束允许最多`n = 100000`和`m = 300000`，它立即排除了对边或顶点排列的任何指数或二次推理。 任何涉及搜索订单或重复检查每次删除周期的操作都会太慢。 

一个微妙的点是，同一对顶点之间允许有多个边，并且它们是独立处理的。 根据每条边是否适合所选的非循环结构，独立地选择或删除每条边。 

一个幼稚的错误是尝试使用 DFS 循环检测直接中断循环并删除每个找到的循环的一个边缘。 这会失败，因为循环重叠并且贪婪删除可能会删除远远超出必要的数量，很容易低于所需的数量`m/2`临界点。 

另一个错误是尝试对原始图进行完整的拓扑排序。 仅当图已经是 DAG 时才有效，但不能保证这一点。 

## 方法

 强力解释将尝试测试边的子集，检查所选子集是否是非循环的且足够大。 即使检查单个子集也需要循环检测`O(n + m)`，并且有`2^m`子集，这是完全不可行的。 

一个更结构化的暴力想法是分配顶点的顺序并仅保持边与其一致。 这总是会产生一个非循环图，但挑战在于找到一种保留至少一半边的排序。 搜索所有排列也是不可能的。 

关键的观察结果是，顶点的每个全排序都会将边划分为两个不相交的组：按顺序向前移动的边和向后移动的边。 前向边缘始终形成 DAG。 如果我们选择身份顺序`1 to n`，我们得到一个有效的子集。 如果我们选择相反的顺序，我们会得到另一个有效的子集。 每条边都属于这两个子集之一，因为对于任何边`a -> b`， 任何一个`a < b`或者`a > b`。 

这立即意味着两个子集一起覆盖所有边缘，因此其中一个必须包含至少一半的边缘。 选择较大的子集可以保证非循环性和大小要求。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 枚举子集/循环检查 | O(2^m) | O(2^m) | O(米) | 太慢了 |
 | 二阶划分（正向与反向） | O(n + m) | O(米) | 已接受 |

 ## 算法演练

 我们使用固定的顶点顺序构造两个候选边集。 

首先我们对待自然秩序`1, 2, ..., n`作为拓扑顺序候选者并收集从较小索引到较大索引的所有边。 

其次我们考虑相反的顺序`n, ..., 1`并收集按该顺序前进的所有边，这对应于其中的边`a > b`在原来的编号中。 

然后我们选择这两组中较大的一个。 

### 步骤

 1. 读取所有边并为其分配输入索引，以便我们稍后可以输出它们。 此索引很重要，因为输出需要原始边缘 ID。 
2. 初始化两个列表，一个用于边，其中`a < b`另一个用于边缘，其中`a > b`。 每个列表代表与不同总排序一致的边。 
3. 对于每条边，比较其端点。 如果`a < b`，与自然顺序一致，被添加到第一个列表中。 否则与相反的顺序一致并添加到第二列表中。 
4. 比较两个列表的大小。 选择较大的一个，因为我们必须保证至少`m/2`边缘。 
5、输出`YES`，然后是所选列表的大小，然后是其边缘的索引。 

这样做的原因是每条边都恰好分配给两个列表之一，因此它们的大小总和为`m`。 因此，至少一个列表的大小必须至少为`m/2`。 两个列表都对应于与全序一致的边，这保证了非循环性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    forward = []
    backward = []
    
    for i in range(1, m + 1):
        a, b = map(int, input().split())
        if a < b:
            forward.append(i)
        else:
            backward.append(i)
    
    if len(forward) >= len(backward):
        chosen = forward
    else:
        chosen = backward
    
    print("YES")
    print(len(chosen))
    print(*chosen)

if __name__ == "__main__":
    solve()
```该实现依赖于边缘的直接划分。 索引循环很重要，因为输出需要原始边缘 ID，因此我们存储`i`对于读取的每个边缘。 

不需要超出原始边缘的图形结构。 整个解决方案基于比较端点并相应分组。 

一个常见的实现错误是忘记边在输入顺序中是 1 索引的。 另一个是意外地重新计算或修改边列表而不是保留索引。 

## 工作示例

 ### 示例轨迹 1

 考虑输入：```
n = 3, m = 3
1 -> 2
2 -> 3
3 -> 1
```我们将边缘一一处理。 

| 边缘 | a < b | 转发列表 | 向后列表 |
 | ---| ---| ---| ---|
 | 1->2 | 是的 | [1] | []|
 | 2->3 | 是的 | [1,2]| []|
 | 3->1 | 没有| [1,2]| [3] |

 我们比较大小：向前有 2 个边缘，向后有 1 个边缘。 我们选择前进。 

选定的边在排序下形成 DAG`1 < 2 < 3`，因此没有剩余循环。 

这演示了如何通过丢弃后向边缘来隐式破坏循环。 

### 示例轨迹 2

 考虑输入：```
n = 2, m = 5
1 -> 2
1 -> 2
1 -> 2
2 -> 1
2 -> 1
```我们处理：

 | 边缘 | a < b | 转发列表 | 向后列表 |
 | ---| ---| ---| ---|
 | 1->2 | 是的 | [1] | []|
 | 1->2 | 是的 | [1,2]| []|
 | 1->2 | 是的 | [1,2,3]| []|
 | 2->1 | 没有| [1,2,3]| [4] |
 | 2->1 | 没有| [1,2,3]| [4,5]|

 我们选择尺寸为 3 的前锋。 

这表明重复的边是独立处理的，并且选择仍然保证至少一半。

 ## 边缘情况

 关键的边缘情况是所有边缘都按降序排列，例如`3 -> 2`,`2 -> 1`,`3 -> 1`。 在这种情况下，自然排序下的前向列表为空，而后向列表包含所有边。 该算法正确地选择了向后列表，这对应于颠倒顺序，从而产生有效的 DAG。 

另一种情况是完全对称的完全有向图，其中每对都有两个方向。 每对都为每个列表贡献了一条边，因此两个列表具有相同的大小。 任一选择都是有效的，并且在相应的排序下仍然是非循环的。 

这些案例证实，即使在对抗性输入分布下，划分策略也是稳定的。
