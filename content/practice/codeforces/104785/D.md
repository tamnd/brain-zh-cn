 ## 解决方案
 ## 问题理解

 我们被赋予了一家公司$n$快递公司，哪里$n$保证能被三整除。 每个快递员都有一个强度值，我们必须将所有快递员准确地划分为$k = n/3$组，每组恰好包含三个人。 

对于每个组，其有效性不是由其内部的最大或最小强度来定义，而是由中值强度来定义，即三者中的第二大值。 目标是将快递员分配为三元组，以便所有组中位数的总和尽可能大。 

因此，任务不是平衡团队或使他们平等，而是仔细决定哪些价值观成为每个三元组的“中间”贡献者。 

约束条件达到$n \le 10^6$，排序后立即强制得出线性算术或线性解。 任何试图直接枚举或模拟组形成的方法都会太慢，因为即使是三元组上的单个组合结构也会爆炸为$O(n^3)$或者更糟。 排序于$O(n \log n)$是可以接受的，并且超出数组几次的任何内容都必须是线性的。 

一个常见的微妙失败案例来自于在没有全局排序的情况下贪婪地对本地三元组进行分组。 例如，具有如下值：

 输入：```
6
1 2 3 100 101 102
```可能会形成幼稚的分组`(100, 101, 102)`和`(1, 2, 3)`，给出中位数`101 + 2 = 103`。 这看起来似乎有道理，但总的来说，这并不是最优的分组逻辑，当值在更具对抗性的分布中交错时，这种贪婪的局部决策就会失败。 

真正的困难在于每个元素恰好参与一个三元组，因此选择谁成为全局中位数会与所有其他选择相互作用。 我们需要一种结构来保证所选的“中间”元素尽可能大，同时仍然是三元组内的有效中位数。 

## 方法

 暴力破解的想法很简单：尝试所有可能的方法将数组划分为三元组，计算每个三元组的中值，并取最大总和。 这原则上是正确的，因为它会检查每个有效的配置。 然而，分区方式的数量$n$将元素分成三个一组的数量是天文数字，并且增长速度超过指数。 即使是为了$n = 30$，这变得不可行，并且在$n = 10^6$，这是完全不可能的。 

关键的观察是我们实际上不需要显式地构造三元组。 我们只关心每个三元组的中间元素。 如果我们对数组进行排序，最佳分组的结构就会受到限制：大值应该充当中位数的“支持”元素，小值应该作为三元组的低端而被牺牲，其余元素自然成为中位数。 

排序后，想象一下从数组的两端向内走。 每个三元组需要一个大的辅助元素和一个围绕选定中位数的小填充元素。 这意味着对于我们选择的每个中位数，我们可以“花费”一个大元素和一个小元素来完成它的组。 由于我们希望中位数尽可能大，因此我们避免过早浪费大值作为中位数的同伴。 

这导致了一个干净的贪婪结构：对数组进行排序并忽略最小的三分之一作为强制填充，最大的三分之一作为强制支持者。 剩下的中间三分之一包含中位数的最佳候选者，但并非所有这些都被直接使用。 相反，正确的中位数按排序顺序定期出现。 

具体来说，升序排序后，最优解从index开始选取元素$k$，然后跳过一个，取一个，然后重复。 这是有效的，因为第一个$k$最小的元素最好用作三元组的“低边”，而最大的元素$k$元素作为“高边”，正好留下$k$位于可以作为中位数最大化的位置的元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最优（排序+贪心选择）|$O(n \log n)$| O(n) | 已接受 |

 ## 算法演练

 我们首先对数组进行排序，以便我们可以推理结构而不是单独的分配。 排序将问题从组合分组转化为位置选择。 

按升序排序后，我们将数组视为三个概念部分：最小元素、最大元素以及从中提取中位数的中间区域。 由于每个组只消耗一个小助手和一个大助手，因此我们保留最小的$k$作为低级合作伙伴和最大的元素$k$元素作为高级合作伙伴。 

中间区域剩下的是$k$对答案有贡献的元素。 然而，我们不会连续地采取它们； 相反，我们选择从索引开始的每隔一个元素$k$，因为在连续的中位数之间，我们必须考虑有效三元组中辅助元素的分配。 

1. 将数组按升序排序。 
2.让$k = n/3$。 
3. 初始化变量`answer = 0`。 
4.从索引开始$k$，迭代数组并选取每个第二个元素，直到$k$元素被选择。 
5. 将每个选定的元素添加到`answer`。 
6. 输出`answer`。 

跳过所有其他元素的原因是，每个选定的中位数隐式为其三元组中的一个较小和一个较大元素保留空间，并且排序结构确保始终可以填充这些角色，而不会干扰其他选定的中位数。 

### 为什么它有效

 一旦数组排序完毕，任何有效的分组都可以重新排列，以便较小的元素永远不会出现为中位数，除非有必要。 每个中位数必须至少有一个比它小和一个比它大的元素。 通过保留最小的$k$元素作为有保证的小伙伴和最大的$k$作为有保证的大同伴，我们完全隔离$k$可以采取中位数的位置。 

交替选择保证没有两个中位数竞争相同的辅助元素，因为在每两个选定的中位数之间存在与消耗的支持元素相对应的结构分离。 这确保了可行性，同时最大化总和，因为我们总是从允许的中值区域中选择最大的可用候选者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    a.sort()
    k = n // 3
    
    ans = 0
    
    # pick medians: indices k, k+2, ..., k+2*(k-1)
    for i in range(k):
        idx = k + 2 * i
        ans += a[idx]
    
    print(ans)

if __name__ == "__main__":
    solve()
```解决方案首先对数组进行排序，这很重要，因为所有结构推理都依赖于相对顺序。 变量$k$代表我们将形成多少个三元组，所以我们准确地期望$k$中位数对最终总和作出贡献。 

循环仔细选择从以下位置开始的索引$k$并且每次跳两级。 起始偏移量$k$避免最小的元素，这些元素在每个三元组中被保留为强制低同伴。 两个步骤确保每个选定的中位数都由一个元素分隔，该元素充当有效分组的结构间距。

 ## 边缘情况

 一种边缘情况是所有值都相同。 对于输入：```
6
5 5 5 5 5 5
```排序不会改变数组，并且$k = 2$。 该算法选择索引 2 和 4，两者都等于 5，给出结果 10。任何分组都会产生相同的结果，并且算法保持一致，因为每个元素都是可互换的，因此中值选择模式并不重要。 

另一个边缘情况是最小的有效输入：```
3
1 2 3
```这里$k = 1$，排序后我们选择索引 1（从 0 开始），即值 2。这正是唯一可能的三元组的中位数，确认索引逻辑即使在边界大小上也与定义一致。
