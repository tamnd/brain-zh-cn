 ## 解决方案
 ## 问题理解

 每个输入行描述一个酒瓶体积，以十进制数字后跟字母表示`L`。 例如，不同的行可能描述完全相同的数量，即使它们在语法上看起来不同`1.0L`和`1L`代表相同的值。 任务是为每个不同的卷分配一个小写单词，并确保相同的卷始终接收相同的单词。 

因此，输出不是对数值本身的计算，而是以十进制形式给出的实数等价类的一致标记。 每当卷稍后再次出现在输入中时，它必须重复使用相同的指定标签，而不是创建新标签。 

约束条件`n ≤ 10000`意味着任何直接比较每对值的解决方案都会太慢，因为这会导致大约`10^8`最坏情况下的比较。 这促使我们采用散列或标准化策略，其中每个值在恒定时间内转换为规范表示，并存储在字典中。 

一个微妙的困难来自浮点表示。 将每个值解析为 Python 的简单方法`float`并将其用作字典键可能会在十进制解析引入精度伪影的边缘情况下失败。 例如，两个输入`0.1L`和`0.10L`显然应该是相同的，但浮点解析有时会根据表示和语言引入微小的舍入差异。 另一种边缘情况是小数点后有很多位的值，最多 10 位，其中二进制浮点不精确。 

正确的方法必须确保两个数值相等的十进制字符串始终映射到相同的内部键，而不管格式差异如何。 

## 方法

 暴力策略将通过解析两个字符串并检查数字相等性，将每个传入的卷与所有先前看到的卷进行比较。 每次比较都涉及解析十进制字符串并可能对其进行标准化，从而导致总体操作次数为二次方。 如果有 10000 个瓶子，则需要进行 1 亿次比较，这在 Python 中太慢了，因为每次比较都涉及字符串解析或浮点处理。 

关键的观察结果是输入已经是具有有限精度的结构化十进制格式。 我们可以通过删除小数点并跟踪小数位数将每个值转换为规范的整数表示形式，而不是依赖浮点运算。 当且仅当两个值的标准化整数形式在对齐小数位数后匹配时才相等。 

一旦每个卷被转换为规范密钥，我们只需要在使用哈希映射之前检查它是否已经被见过。 如果没有，我们分配一个新标签。 这将整个问题简化为字符串上的线性时间哈希。

 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 规范化的最佳散列 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们想要每个卷的表示，使相等性检查准确且独立于格式。 

1.读取卷字符串并删除尾随`L`，仅保留数字部分。 
2. 将数字字符串拆分为整数部分和小数点附近的小数部分。 如果不存在小数点，则将小数部分视为空。 
3. 通过删除整数部分中的前导零和删除小数部分中的尾随零来标准化表示。 如果修剪后小数部分变空，我们就完全丢弃小数。 这确保了`1`,`1.0`， 和`01.000`全部折叠成同一个键。 
4. 将规范键构造为包含清理后的整数部分和清理后的小数部分的元组。 该元组唯一地表示十进制形式的实数，没有浮点错误。 
5. 使用字典将每个唯一键映射到生成的单词。 当遇到新键时，分配下一个未使用的单词标识符。 当相同的键再次出现时，重复使用之前分配的单词。 

### 为什么它有效

 当且仅当在删除格式伪像（例如前导零和冗余尾随零）后，两个十进制字符串的整数和小数位匹配时，两个十进制字符串才表示相同的数字。 规范化步骤为输入格式中可表示的每个实值强制执行唯一的规范形式。 由于字典使用这种规范形式作为键，因此值空间中的相等性会转换为字符串表示形式中的相等性，从而保证标签的一致性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def normalize(s: str):
    if s.endswith("L"):
        s = s[:-1]

    if "." in s:
        a, b = s.split(".")
    else:
        a, b = s, ""

    a = a.lstrip("0")
    if a == "":
        a = "0"

    b = b.rstrip("0")

    if b == "":
        return (a, "")

    return (a, b)

def solve():
    n = int(input())
    mp = {}
    out = []
    counter = 0

    for _ in range(n):
        s = input().strip()
        key = normalize(s)

        if key not in mp:
            mp[key] = f"w{counter}"
            counter += 1

        out.append(mp[key])

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```实现的核心是`normalize`函数，它确保相同数字的语法上不同的表示形式折叠成相同的元组。 字典`mp`存储从标准化数字到指定单词的第一次看到的映射。 

的选择`tuple(int_part, frac_part)`完全避免浮点并保证精确的比较语义。 生成的名称`w0, w1, ...`仅用作占位符； 只要相同的键重用相同的字符串，任何一致的小写字符串都可以满足问题要求。 

一个常见的实施错误是使用`float(s[:-1])`作为字典键。 这可能会导致长小数输入的精度损失，并且可能会错误地合并不同的值或分离相等的值。

 ## 边缘情况

 一个棘手的情况是，相同的数值以多种视觉上不同的形式书写。 例如，`01.0L`,`1L`， 和`1.000L`都代表相同的体积。 经过分裂和归一化后，每一个都成为整数部分`"1"`和空小数部分，因此它们折叠成相同的字典键并接收相同的标签。 

另一种边缘情况涉及仅尾随零不同的小数值，例如`0.30L`和`0.3L`。 归一化步骤会修剪小数部分的尾随零，因此两者都变为`(0, "3")`，即使输入格式精度不同，也能确保正确分组。
