 ## 解决方案
 ## 问题理解

 两名玩家各自控制一个战斗单位。 每个单位以固定的间隔重复发射导弹。 射击不会立即造成伤害，它会在发射后半秒落地。 一旦单位开火，它必须等待装填时间才能再次开火。 两支部队在零时开始完全准备就绪，并立即发射第一枚导弹。 

每枚导弹落地时都会使对手的生命值减少固定数量。 一旦一个单位的生命值变为零或负值，它就会被摧毁。 由于双方都可以同时开火，并且导弹的飞行延迟相同，因此，如果最后的破坏性射击同时落地，两个单位都可能“立即”死亡。 

任务是严格确定哪个单位在另一个单位被摧毁后仍然具有积极的健康状况，假设两个单位都以唯一可用的最佳方式行事，即只要允许开火就开火。 

输入由两个三元组组成。 第一个三元组描述了玩家单位的生命值、每次射击的伤害和装弹时间。 第二个三元组以相同的格式描述了玩家二的单位。 输出要么是玩家一获胜，玩家二获胜，要么两者都不能在生存时间上严格领先。 

约束很小，所有值最大为 1000。这排除了对繁重数据结构或高级优化的任何需要，但如果简单地模拟，随着时间的推移，它仍然为许多镜头留下了空间。 

小时间步长的直接模拟具有误导性，因为事件以不规则的间隔稀疏发生。 另一个常见错误是忽略 0.5 秒的行进延迟，当两个单位在同一周期内进行致命打击时，这可能会导致错误的排序。 

当两个单位以相同的命中指数互相摧毁时，就会出现微妙的边缘情况。 例如，如果两者在第三枚导弹落地后生命值都达到零，即使其中一枚导弹提前实时发射，两者也会同时死亡，因为两个伤害事件同时落地。 

## 方法

 暴力解释将模拟连续时间内的战斗。 每个单位都有一个下一次开火计时器，我们将时间提前到下一次开火事件，安排伤害到达时间加 0.5。 我们继续按时间顺序应用损坏事件，直到一个或两个生命值降至零。 

此模拟是正确的，但事件数量可能很大。 每个单位最多可以发射大约 1000 次，因为生命值和伤害以 1000 为界，每次射击的伤害可以小至 1。完整的事件驱动模拟仍然在限制范围内，但逐步穿越时间或维护细粒度的时间线是不必要的开销。 

关键的观察结果是，0.5 秒行程延迟内的确切顺序并不重要。 双方的每次射击都会经历相同的延迟，因此相对顺序仅取决于杀死一个单位需要多少次射击以及这些射击发生的频率。 

我们不是模拟每枚导弹，而是计算杀死每个单位需要多少次命中。 如果玩家 1 的生命值为 h1，每次攻击受到 d2 伤害，则所需的攻击次数为 ceil(h1 / d2)。 这些命中以 t2 秒的固定间隔发生，第 k 个命中在时间 (k−1)·t2 + 0.5 处到达。 这同样适用于玩家二号。 

比较两次死亡时间直接就能看出胜负。 比较时，共享的 +0.5 延迟被取消，因此只有触发时间表很重要。

 ## 算法演练

1. 计算一名玩家需要击中多少次才能死亡。 这是满足 k1·d2 ≥ h1 的最小整数 k1。 这代表玩家二号必须成功撞击多少次。 
2. 以同样的方式计算玩家二需要死亡多少次，从 h2 和 d1 生成 k2。 
3. 使用射击间隔将命中计数转换为死亡时间。 玩家二在时间 (k1 − 1)·t2 + 0.5 处杀死玩家一，因为第一次击中是在第一次射击之后落地，并且后续每次击中​​的间隔为 t2。 玩家一在 (k2 − 1)·t1 + 0.5 时刻杀死玩家二。 
4. 比较这两个时间。 如果第一次时间较小，则玩家二更早获得致命一击，因此玩家二获胜。 如果第二次较小，则一号玩家获胜。 
5. 如果时间相等，则两个单位同时受到最终致命伤害，并且严格意义上都没有存活更长时间，因此结果是平局。 

它之所以有效，是因为每个单位的伤害过程都是时间上统一的算术级数。 每个相关事件仅由导致死亡的命中指数决定。 由于所有命中共享相同的固定延迟，因此相对顺序仅取决于致命一击之前的间隔数量，而不取决于两个时间线之间的任何中间交互。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    h1, d1, t1 = map(int, input().split())
    h2, d2, t2 = map(int, input().split())

    def hits_needed(h, d):
        return (h + d - 1) // d

    k1 = hits_needed(h1, d2)
    k2 = hits_needed(h2, d1)

    time_2_kills_1 = (k1 - 1) * t2
    time_1_kills_2 = (k2 - 1) * t1

    if time_1_kills_2 < time_2_kills_1:
        print("player one")
    elif time_2_kills_1 < time_1_kills_2:
        print("player two")
    else:
        print("draw")

if __name__ == "__main__":
    solve()
```核心实现将所有内容简化为两个整数比较。 辅助函数使用整数算术安全地计算上限除法，避免浮点问题。 

在比较中故意省略了 0.5 秒的行程延迟，因为这对于两名玩家的最终击杀命中来说是相同的，因此不会影响排序。 包含它只会为两个计算时间添加相等的常数偏移。 

## 工作示例

 考虑第一个样本输入：

 玩家一的伤害较弱，但具有不同的重新加载时间权衡。 玩家二的每次攻击伤害输出更高，这减少了所需的攻击次数。 

| 数量 | 玩家 1 杀死玩家 2 | 玩家 2 杀死玩家 1 |
 | ---| ---| ---|
 | 需要点击量 | 天花板(30 / 15) = 2 | 天花板(30 / 10) = 3 |
 | 消磨时间 | (2−1)·19 = 19 | (2−1)·19 (3−1)·10 = 20 | (3−1)·10 = 20 | (3−1)·10 = 20

 玩家一的击杀时间是19，而玩家二需要20。尽管玩家一的每次伤害较低，但所需的命中次数较少，因此玩家一的致死射击到达较早，这与预期的获胜者相符。 

现在考虑一个类似对称的交换情况：

 | 数量 | 玩家 1 杀死玩家 2 | 玩家 2 杀死玩家 1 |
 | ---| ---| ---|
 | 需要点击量 | 天花板(30 / 10) = 3 | 天花板(30 / 15) = 2 |
 | 消磨时间 | (3−1)·10 = 20 | (3−1)·10 = 20 | (3−1)·10 = 20 (2−1)·19 = 19 | (2−1)·19

 这里，玩家二号在时间 19 时较早死亡，因此玩家二号获胜。 

这些例子表明，获胜者更多地取决于重新加载速度和所需命中次数之间的相互作用，而不是仅仅取决于原始伤害值。

 ## 边缘情况

 当两个单位死于相同的射击指数时，就会出现一种重要的极端情况。 考虑同等的生命值和对称的伤害/重装。 两者计算相同的命中数和相同的射击时间表，产生相同的击杀时间。 该算法比较相同的时间并正确返回平局，这与两个死亡事件由于相同的 0.5 秒延迟而同时发生的事实相匹配。 

另一个微妙的情况是，当一个单位造成极高的伤害并且只需一击即可杀死对手。 在这种情况下，该方的计算时间变为零，因为 (1−1)·t = 0。这正确地模拟了第一次射击立即决定了结果，并且对手的任何较慢的击杀计划都无法在第一次撞击时间比较解决之前进行干预。 

最后一种情况是重新加载时间差异很大。 一个重装速度非常慢但伤害较高的单位仍然可能会输给一个快速的低伤害单位，因为所需的命中次数会增加间隔数，从而将其最终命中的时间推迟。 该算法自然地处理这个问题，因为这两个因素都被编码在相同的死亡时间线性表达式中。
