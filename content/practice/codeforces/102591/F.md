 ## 解决方案
 ## 问题理解

 我们的学生人数为奇数，每个学生都有独特的实力值。 我们必须让一名学生没有搭档，并将所有剩余的学生分成两人一组。 一对贡献其两个成员中较小的力量，因此强度为 10 和 3 的一对贡献 3。对于每个可能被排除在外的学生，我们需要所有对的最大可能总贡献。 

输出不是一个值。 它包含每个原始学生的一个答案，其中答案位于位置`i`描述如果该学生是未参加的学生的最佳总分。 

这些限制是这个问题有趣的主要原因。 高达`3 * 10^5`学生们，尝试所有可能的删除并重新计算每个的最佳配对将需要大约二次工作，大约`9 * 10^10`最坏情况下的操作。 这远远超出了竞争性编程解决方案所能承受的范围。 我们需要找到一种模式，让我们在一次排序后可以一起处理每个学生。 

一些边缘情况可能会破坏仅处理常见情况的实现。 最小的可能输入只有三名学生。 例如，凭借实力`3 1 2`，用实力去除学生`3`树叶`[1,2]`，给出分数`1`。 去除`1`树叶`[2,3]`, 给予`2`。 去除`2`树叶`[1,3]`, 给予`1`。 正确的输出是`1 2 1`。 始终假设最大的学生参与一对的解决方案在这里可能会失败。 

另一个常见的错误是忘记被删除的学生在排序后更改了所有后续位置的奇偶性。 用于输入`1 2 3 4 5`，如果我们删除`3`，剩余的排序列表是`1 2 4 5`。 最优分数是`1 + 4 = 5`。 将原始指数视为没有任何变化会给出错误的所选位置集。 

## 方法

 直接的解决方案首先尝试删除所有可能的学生。 除去一名学生后，我们对剩余的优势进行排序或保留，并建立最佳配对。 对于偶数学生的固定排序列表，很容易找到最佳策略：从每对中取出尽可能大的较小成员。 这意味着答案是从末尾开始计算的每个第二个元素的总和，或者等效地按升序排列的偶数索引处的每个元素。 

暴力方法是正确的，因为它检查了每个可能被删除的学生所需的确切情况。 问题在于重复工作量。 有`n`可能的移除，并且几乎每一个都需要处理`n`学生，导致`O(n^2)`避免不必要的排序后工作。 和`n = 300000`，那已经不可能了。 

关键的观察是，我们实际上不需要为每次删除重建剩余的数组。 对所有学生进行一次排序。 令排序后的强度为`a[0], a[1], ..., a[n-1]`。 如果我们删除位置上的元素`r`，剩余数组中选定的元素正是之前的原始偶数索引`r`以及之后的原始奇数索引`r`。 

原因是指数移动。 删除位置之前的元素保留其索引，因此偶数位置仍然是所选位置。 删除位置之后的元素向左移动一步，因此原始奇数索引变成偶数索引并有助于答案。 

这将问题转化为维护两个简单的和。 偶数索引处的值的前缀和给出了移除左侧的贡献。 奇数索引处的值的后缀和给出了右侧的贡献。 每个答案都是这两个值的组合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1、按照实力对学生进行排序，保持原来的位置。 排序使我们能够推断出最终的配对顺序，因为配对的贡献仅取决于哪个学生较弱。 
2. 构建前缀数组，其中`pref[i]`存储位置之前具有偶数索引的排序元素的总和`i`。 当学生处于某个位置时`i`被删除，之前的所有偶数位置`i`保持不变，仍然做出贡献。 
3. 构建后缀数组，其中`suf[i]`存储从位置开始具有奇数索引的已排序元素的总和`i`到最后。 删除位置后`i`，其后的每一个元素都左移一位，于是原来的奇数位置就变成了选中的偶数位置。 
4. 对于每个排序位置`i`, 计算`pref[i] + suf[i + 1]`。 这是删除排序位置的学生的答案`i`。 前缀处理未更改的左侧，后缀处理移动的右侧。 
5. 使用排序步骤中保存的原始索引将答案恢复为原始输入顺序。 所需的输出遵循学生给出的顺序。 

为什么有效：对于任何固定的剩余学生集，最佳配对始终采用从最小元素开始的已排序剩余序列中的每隔一个元素。 删除一个元素仅影响该元素之后位置的奇偶性。 在删除位置之前，所选择的索引恰好是原始偶数索引。 之后，所选择的索引正是原来的奇数索引。 该算法精确计算这两个组，因此每个产生的值都是其相应移除学生的最佳分数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = list(map(int, input().split()))

    arr = sorted((value, idx) for idx, value in enumerate(s))

    pref = [0] * (n + 1)
    for i, (value, _) in enumerate(arr):
        pref[i + 1] = pref[i]
        if i % 2 == 0:
            pref[i + 1] += value

    suf = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suf[i] = suf[i + 1]
        if i % 2 == 1:
            suf[i] += arr[i][0]

    ans = [0] * n
    for i, (_, original_idx) in enumerate(arr):
        ans[original_idx] = pref[i] + suf[i + 1]

    print(*ans)

if __name__ == "__main__":
    solve()
```排序步骤存储强度和原始位置。 配对参数需要强度顺序，而原始索引需要将最终答案放回输入顺序。 

前缀构造仅在偶数排序位置添加值。 它故意使用`pref[i]`回答位置时`i`，因为删除的元素本身不得包含在内。 

后缀构造从右向左扫描并收集奇数排序位置的值。 移除位置时`i`，右侧部分开始于`i + 1`，这就是为什么答案使用`suf[i + 1]`。 

Python 整数自动处理可能的总和大小。 最大可能的答案可能是`1.5 * 10^14`，这会在需要手动处理的语言中溢出 32 位整数类型。

 ## 边缘情况

 当只有三个学生时，该算法仍然有效，因为前缀和后缀数组包含足够的边界位置。 用于输入`3 1 2`，删除排序后的第一个元素仅使用后缀贡献，删除中间元素使用前缀贡献，删除最大元素留下最小值作为唯一的对贡献。 

当被删除的学生接近开始或结束时，索引移位是最常见的错误来源。 用于输入`1 2 3 4 5`，去除`1`树叶`[2,3,4,5]`。 答案使用删除位置后的原始奇数索引，给出`3 + 5 = 8`。 后缀数组恰好从下一个位置开始，因此它可以正确捕获此移位。 

对于非常大的强度，对的数量仍然可能足够大，以致 32 位算术失败。 输入如`1000000000 1 999999999`即使只有三个学生，也会产生接近 10 亿个答案，而更大的情况可能会超出 32 位限制。 该实现使用 Python 整数，因此累加保持准确。
