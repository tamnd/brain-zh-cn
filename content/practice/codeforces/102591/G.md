 ## 解决方案
 # 问题理解

 我们有一个长方形的板，上面填满了来自`1`到`N*M`正好一次。 该板是由包含以下内容的单个单元创建的`1`通过在外部重复添加新的行或列。 添加行后，其单元格将从左到右填充之前未出现过的最小数字。 添加列时，其单元格将以相同的方式从上到下填充。 

任务是恢复可能创建该板的任何操作序列。 输出是按时间顺序描述这些操作的字母序列。 

约束条件允许`N`和`M`最多`500`，所以董事会可以包含`250000`细胞。 尝试许多可能的构造历史的解决方案是不可能的，因为可能的操作顺序的数量呈指数增长。 预期的解决方案只需要检查电路板几次，从而导致大致线性的复杂性。 

主要陷阱是假设最大值始终位于右下角。 他们不是。 最后一个操作可以从任意一侧添加行或从任意一侧添加列。 另一个常见的错误是忘记删除一层后，必须仅在剩余矩形内搜索下一个最大值，而不是在原始板内搜索。 

例如：```
1 2
3 4
```粗心的解决方案可能总是会删除底行和输出`D`。 这在这里是有效的，但请考虑：```
3 1
4 2
```最后一个操作必须添加左列，因为最大的两个值是`3,4`垂直。 移除错误的一侧会破坏施工顺序。 

另一个边缘情况是单行：```
1 2 3 4
```唯一可能的操作是列添加。 在不检查当前尺寸的情况下对称地处理行和列可能会产生无效的移除。 

## 方法

 直接的方法是尝试重建流程。 开始于`1`，我们可以尝试下一步所有可能的操作，进行模拟，并将结果与​​目标板进行比较。 这是正确的，因为每条有效的历史都代表在探索的选择中。 问题是每个状态可以分为四种选择，并且构建需要`N+M-2`运营。 搜索空间约为`4^(N+M)`，这远远超出了 500 左右尺寸的处理能力。 

有用的观察来自于回顾过程。 每时每刻，已经放置的数字都恰好是序列的前缀`1,2,3,...`。 如果当前矩形有面积`A`，然后最后一个操作添加了一些恰好包含以结尾的数字的边`A`。 一行的长度`k`必须包含：```
A-k+1, A-k+2, ..., A
```从左到右。 一列从上到下必须包含相同的序列。 

这将问题从寻找历史转变为反复剥离最后一层。 在每一步中，我们只需要检查剩余矩形的四个边框。 一旦边框与所需的连续值匹配，我们就知道最后一个操作并可以将其删除。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(4^(N+M))`|`O(N*M)`| 太慢了|
 | 最佳|`O(N*M)`|`O(N*M)`| 已接受 |

 ## 算法演练

 1. 保留四个指针来描述当前剩余的矩形：`top`,`bottom`,`left`， 和`right`。 最初这是整个板。 还保留`area`，当前矩形内的单元格数量。 
2. 检查顶行是否包含以下值`area - width + 1`到`area`按递增顺序。 如果是，则上次操作是`U`，因此删除该行并将面积减少行长度。 
3. 如果顶行不匹配，则以同样的方式检查底行。 如果匹配，则最后一次操作是`D`。 
4. 使用相同的规则检查左列和右列。 匹配的左列表示最后一次操作是`L`，并且匹配的右列表示最后一次操作是`R`。 
5. 存储每个删除的操作。 删除按相反的时间顺序发生，因此在打印之前反转收集的操作。 

不变的是，在每次移除之前，剩余的矩形正是最后一个构建步骤之前的棋盘状态。 它的单元格精确地包含来自`1`到`area`，因此最近添加的一侧必须包含该前缀的最大数字。 由于该算法仅删除满足此属性的一侧，因此每次删除都对应于有效的先前操作。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    top, bottom = 0, n - 1
    left, right = 0, m - 1
    area = n * m
    ans = []

    while top < bottom or left < right:
        done = False

        width = right - left + 1
        need = list(range(area - width + 1, area + 1))

        if a[top][left:right + 1] == need:
            ans.append('U')
            top += 1
            area -= width
            done = True
        elif a[bottom][left:right + 1] == need:
            ans.append('D')
            bottom -= 1
            area -= width
            done = True
        else:
            height = bottom - top + 1
            need = list(range(area - height + 1, area + 1))

            col = [a[i][left] for i in range(top, bottom + 1)]
            if col == need:
                ans.append('L')
                left += 1
                area -= height
                done = True
            else:
                col = [a[i][right] for i in range(top, bottom + 1)]
                if col == need:
                    ans.append('R')
                    right -= 1
                    area -= height
                    done = True

        if not done:
            break

    print(''.join(reversed(ans)))

if __name__ == "__main__":
    solve()
```该代码仅保留当前矩形边界以及其中剩余的单元格数量。 这`area`变量是仍然应该存在的最大值，这让我们可以立即计算最后添加的边框的预期值。 

比较的顺序与相反过程相同：首先是可能的最后一行，然后是可能的最后一列。 该问题保证每个阶段至少有一方有效。 删除一侧后，相应的边界在下一次迭代之前向内移动。 

Python整数在这里不需要特殊处理，因为最大值只是`250000`。 主要实施细节正在更新`area`由删除的细胞的确切数量决定，因为下一个预期序列取决于它。

 ## 边缘情况

 对于单细胞情况：```
1 1
1
```起点已经等于目标。 循环永远不会运行，因为没有要删除的边框，并且答案是空字符串。 

对于单排板：```
1 4
1 2 3 4
```当前的矩形永远不会丢失一行，因为删除唯一的一行将不会留下任何板。 该算法检查列并一一删除它们，匹配唯一可能的结构。 

对于最终操作不在底部或右侧的板：```
2 2
3 1
4 2
```最大值位于第一列中。 该算法检查所有四个边界并找到包含最终连续值的左列，因此它会删除`L`而不是依赖一个固定的方向。 这保留了反向构造不变式。
