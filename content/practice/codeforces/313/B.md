 ## 解决方案
 ## 问题理解

 我们得到一个仅由字符“.”组成的字符串。 和 ”＃”。 任务是有效地回答多个查询。 每个查询都会询问，在从位置 _l_ 到 _r_ 的子字符串中，某个字符后面紧跟着相同字符的次数有多少次。 例如，在子字符串“..#..”中，连续的相同字符对是位置1-2和4-5。 查询需要此类位置的计数。 

输入字符串最长可达10万个字符，查询次数也最多可达10万个。 这意味着在最坏的情况下，扫描每个查询的每个子字符串的简单方法最多需要 10^10 次操作，这远远超出了 2 秒时间范围的可接受限制。 因此，解决方案必须避免重复扫描重叠的子字符串。 

非明显的边缘情况包括具有所有相同字符的字符串、交替字符或跨越整个字符串的查询。 例如，如果字符串是“######”并且查询是 1 到 6，则正确答案是 5，因为前五个字符中的每一个都与其相邻字符形成一对。 只计算唯一字符或忘记最后一对字符的粗心方法会产生错误的输出。 类似地，对于像“.#.#.#”这样的字符串，如果没有连续的字符匹配，则每个长度超过一个字符的查询都可能返回零，并且简单的方法必须正确处理边界。 

## 方法

 暴力方法很简单：对于每个查询，从起始索引 _l_ 迭代到 _r_−1，检查当前字符是否等于下一个字符，并递增计数器。 这工作正常，但在最坏情况下其复杂度为 O(m·n)。 在约束 n、m ≤ 10^5 的情况下，这可能会导致大约 10^10 次操作，这是不可行的。 

关键的观察是我们需要的信息——连续相等字符的计数——可以在线性时间内预先计算出整个字符串。 定义一个数组`prefix`这样`prefix[i]`是从字符串开头到索引的连续相同字符对的数量`i`。 那么，对于查询 (l, r)，答案很简单`prefix[r-1] - prefix[l-1]`。 这有效是因为`prefix[r-1]`计算直到位置 r-1 的所有对，并且`prefix[l-1]`计算位置 l 之前的所有对，因此它们的差给出了查询范围内的对的数量。 这将每个查询的查询处理减少到 O(1)，从而导致总复杂度为 O(n + m)，这是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n·m) | O(1) | O(1) | 太慢了 |
 | 前缀和| O(n + m) | O(n) | 已接受 |

 ## 算法演练

 1. 初始化一个长度为 n+1 的前缀和数组，所有值设置为零。 该数组将存储连续相同字符的累积计数。 
2. 从索引 1 到 n−1 迭代字符串。在每个位置 i，检查当前字符是否`s[i]`等于前一个字符`s[i-1]`。 如果是这样，则增加计数：`prefix[i] = prefix[i-1] + 1`。 否则，设置`prefix[i] = prefix[i-1]`。 
3. 对于由 l 和 r 定义的每个查询，将答案计算为`prefix[r-1] - prefix[l-1]`。 这给出了位置 i 的数量，使得`s[i] == s[i+1]`对于 [l, r-1] 中的 i。 
4. 输出每个查询的计算答案。 

为什么它有效：前缀数组维护一个不变量`prefix[i]`始终等于从字符串开头到位置 i 的连续相等字符对的数量。 通过从 r−1 处的前缀值中减去 l−1 处的前缀值，我们隔离了完全位于查询范围内的对的计数。 这可以避免重复计算并确保所有查询边界的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)
prefix = [0] * (n + 1)

for i in range(1, n):
    prefix[i] = prefix[i-1] + (1 if s[i] == s[i-1] else 0)

m = int(input())
for _ in range(m):
    l, r = map(int, input().split())
    print(prefix[r-1] - prefix[l-1])
```第一部分读取字符串并初始化前缀和数组。 从 1 迭代到 n−1 确保我们将每个字符与其左邻居进行比较。 对于查询，减去`prefix[l-1]`从`prefix[r-1]`在 Python 中使用基于 0 的数组时，正确解释了问题中基于 1 的索引。 通过仔细地将数组索引与问题的索引方案对齐可以避免相差一错误。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + m) | O(n) 构建前缀数组，O(1) 每个查询 m 个查询 |
 | 空间| O(n) | 长度为 n+1 的前缀数组 |

 给定 n、m ≤ 10^5，这会导致最多 2·10^5 次前缀操作和 10^5 次查询操作，完全在 2 秒的时间限制内。 前缀数组的内存使用量约为 0.8 MB，与 256 MB 相比可以忽略不计。
