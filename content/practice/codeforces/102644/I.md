 ## 解决方案
 ## 问题理解

 该问题描述了一个最多有 200 个顶点的有向图。 路径是精确的序列`k`有向边，并且顶点或边可能出现多次。 对于每个查询，我们都会被问到有多少条不同的行走从顶点开始`s`, 结束于顶点`t`，并且恰好包含`k`边缘。 答案必须以模数形式打印`1,000,000,007`。 

输入图最多可以包含 200 个顶点和 200 个查询，而所需的路径长度可以大到`10^9`。 直接模拟路径是不可能的，因为可能的行走次数呈指数增长`k`。 即使是处理每一步的动态编程方法也太慢了，因为`k`不受小值的限制。 顶点数量较少是关键约束：它允许我们在`200 x 200`矩阵。 

粗心的解决方案可能会在多种情况下失败。 如果`k`很大，一次迭代一条边永远不会完成。 例如，使用单边`1 -> 1`并查询`(1, 1, 1000000000)`，答案是`1`，但逐步模拟将需要十亿次转换。 

另一个常见的错误是忘记路径可以重新访问顶点。 对于输入：```
2 2 3
1 2
2 1
1 1 3
```正确的输出是：```
0
```唯一可能的行走在两个顶点之间交替，因此在三个边之后，我们在顶点处结束`2`，不是顶点`1`。 将图视为简单的路径问题会产生不正确的结果。 

第三种边缘情况是空图。 例如：```
3 0 2
1 2 5
3 3 1
```输出是：```
0
0
```因为不存在边，所以无法创建正长度游走。 

## 方法

 蛮力的想法是从起始顶点开始遵循每一个可能的行走。 对于每个查询，我们可以运行深度优先搜索来选择下一条边`k`次数并计算我们到达目的地的次数。 这是正确的，因为它准确地枚举了所有有效的行走。 然而，步行次数可以增加到`n^k`，因此即使只有 200 个顶点的图也变得不可能`k`达到`10^9`。 

更好的第一个观察是我们只关心顶点之间的过渡。 让`A[i][j]`表示是否存在一条边`i`到`j`，或更准确地说，是来自的单边路径的数量`i`到`j`。 矩阵乘法自然地结合了转换。 条目`(i, j)`的`A^2`告诉我们有多少条两条边路径从`i`到`j`，因为考虑了每个可能的中间顶点。 同样的想法延伸到任何长度，所以答案是`(s, t)`的元素`A^k`。 

剩下的问题是`k`可以是巨大的。 二进制求幂就像普通求幂一样解决这个问题。 我们预先计算权力`A^(1), A^(2), A^(4), A^(8)`， 等等。 每一点`k`告诉我们哪些权力应该相乘。 

由于只有 200 个查询，因此最好计算一次幂并重复使用它们。 每个查询最多只需要 30 个矩阵向量样式转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^k) | O(n^k) | O(k) | 太慢了 |
 | 矩阵求幂| O(n^3 log k + qn^2 log k) | O(n^3 log k + qn^2 log k) | O(n^2 log k) | O(n^2 log k) | 已接受 |

 ## 算法演练

 1. 构建邻接矩阵`A`。 价值`A[i][j]`存储来自顶点的直接边的数量`i`到顶点`j`。 由于没有多重边，因此每个条目都是`0`或者`1`。 
2. 预先计算矩阵的幂。 店铺`A`,`A^2`,`A^4`,`A^8`，并继续直到最大可能的位`k`被覆盖。 每个下一个矩阵都是通过将前一个矩阵与其自身相乘而获得的。 
3. 查询`(s, t, k)`，从单位矩阵开始作为当前结果并扫描`k`。 
4.每当有一点`k`设置后，将当前结果乘以相应的预先计算的功率。 
5. 返回行的值`s`， 柱子`t`最终矩阵的。 

二进制求幂起作用的原因是每个正整数都可以表示为 2 的幂之和。 矩阵乘法保留了路径组合的含义，因此乘以所选的幂可以精确地组合所需的边数。 

为什么它有效：在处理一些位之后`k`，维护的矩阵表示使用指数的处理部分的路径数。 当遇到设定位时，乘以`A^(2^i)`将那么多边附加到每个可能的部分路径上。 在所有位都被处理之前，不变量保持为真，此时矩阵等于`A^k`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def multiply(a, b):
    n = len(a)
    bt = [[b[j][i] for j in range(n)] for i in range(n)]
    res = [[0] * n for _ in range(n)]

    for i in range(n):
        ai = a[i]
        ri = res[i]
        for j in range(n):
            s = 0
            bj = bt[j]
            for k in range(n):
                s += ai[k] * bj[k]
            ri[j] = s % MOD
    return res

def solve():
    n, m, q = map(int, input().split())

    mat = [[0] * n for _ in range(n)]
    for _ in range(m):
        a, b = map(int, input().split())
        mat[a - 1][b - 1] = 1

    powers = [mat]
    for _ in range(31):
        powers.append(multiply(powers[-1], powers[-1]))

    ans = []
    for _ in range(q):
        s, t, k = map(int, input().split())
        s -= 1
        t -= 1

        vec = [0] * n
        vec[s] = 1

        bit = 0
        while k:
            if k & 1:
                new_vec = [0] * n
                p = powers[bit]
                for i in range(n):
                    if vec[i]:
                        vi = vec[i]
                        row = p[i]
                        for j in range(n):
                            new_vec[j] = (new_vec[j] + vi * row[j]) % MOD
                vec = new_vec
            k >>= 1
            bit += 1

        ans.append(str(vec[t]))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```矩阵乘法例程使用第二个矩阵的转置副本，以便每个内部循环访问连续的行。 这避免了重复索引列并使 Python 中的三次乘法更快。 

查询阶段不会将两个完整矩阵相乘。 相反，它将起始向量乘以所需的矩阵。 起始向量有一个`1`在源顶点处，表示采用任何边之前的一条空路径。 处理完所有位后，目标位置包含长度的走行数`k`。 

指数循环处理的值高达`10^9`，因此 30 到 31 次迭代就足够了。 在每次累加期间应用模运算，以将值保持在 Python 整数限制内并匹配所需的输出。

| 步骤| 当前指数位 | 矢量状态|

 组合所选的幂后，顶点的值`2`是`2`，它匹配长度为 6 的两个有效游走。

这些示例表明，该算法按长度而不是简单路径对行走进行计数，并且求幂过程可以正确处理小长度和大长度。

 ## 边缘情况

 对于没有边的图，邻接矩阵完全为零。 每个矩阵幂都保持为零，因此每个要求正数步数的查询都会正确返回零。 

对于一个循环，例如：```
2 2 1
1 2
2 1
1 1 1000000000
```邻接矩阵的幂正确地保留了交替运动。 由于指数是按位而不是单独的步骤处理的，因此该解决方案无需模拟十亿次转换即可得出答案。 

对于重复访问，矩阵乘法解释自然包括返回已访问顶点的路径。 不需要特殊处理，因为矩阵幂计算的是行走而不是简单的路径。
