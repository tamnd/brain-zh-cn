 ## 解决方案
 # 问题理解

 该问题给出了一个有向图，其顶点编号为`1`到`n`并询问精确使用的可能行走次数`k`有向边。 步行可能会重用顶点和边，因此任务不是简单的路径。 起始顶点和结束顶点的每个选择都包含在答案中，这意味着我们精确计算所有有效的顶点序列`k`过渡。 结果必须按模打印`1,000,000,007`。 

输入大小是围绕图本身很小而路径长度可能非常大的观察而设计的。 顶点数最多为`100`，因此涉及顶点数三次运算的算法是合理的。 然而，`k`可以达到`10^9`，这排除了任何一次一步处理路径的动态编程解决方案。 计算长度答案的简单递归`1, 2, ..., k`需要大约`10^11`甚至在考虑矩阵运算之前就进行转换，这不符合典型的竞赛限制。 

一些情况很容易破坏简单的实现。 如果`k = 1`，答案就是有向边的数量。 例如：```
3 2 1
1 2
2 3
```答案是`2`，因为唯一的步行是`1 -> 2`和`2 -> 3`。 初始化零长度路径答案的实现也可能会意外地计算三个单个顶点。 

带有循环的图是另一个重要的例子：```
3 3 2
1 2
2 3
3 1
```答案是`3`，因为有效的行走是`1 -> 2 -> 3`,`2 -> 3 -> 1`， 和`3 -> 1 -> 2`。 使用已访问数组进行深度优先搜索会错误地删除这些遍历，因为允许重新访问顶点。 

没有边缘的情况也必须处理：```
2 0 5
```答案是`0`。 任何从全 1 向量开始并忘记不可能进行转换的解决方案都将返回不正确的正值。 

# 方法

 直接的方法是按长度模拟路径。 让`dp[v]`表示当前长度有多少条路径在顶点处结束`v`。 最初，对于长度为零，每个顶点都可以作为起点，因此每个顶点贡献一次空走。 对于每条额外的边，我们通过跟踪所有传出边来更新计数。 这是正确的，因为每一段路程`i + 1`是通过延伸一段长度而形成的`i`多了一条边​​。 

问题是值`k`。 一次更新需要检查边缘，更新次数为`k`。 在最坏的情况下，有接近`n(n - 1)`边缘，所以工作大约是`10^9 * 10^4`，这远远超出了可用时间。 

有用的结构是重复应用一个转换正是矩阵求幂的设计目的。 我们可以将图表示为邻接矩阵`A`， 在哪里`A[i][j]`告诉有多少条直接边从顶点出发`i`到顶点`j`。 在这个问题中，不存在多重边，因此值只有零或一。 

当我们将矩阵相乘时，输入`(i, j)`的`A^2`计算两条边行走的数量`i`到`j`。 同样的推理也适用于更高的幂，所以`A^k`包含长度路径的所有答案`k`。 自从`k`很大时，二进制求幂会减少矩阵乘法的次数`k`到`log(k)`。 

最终答案是每个条目的总和`A^k`，因为每个可能的起始和结束顶点对都会影响总计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(k * 米) | O(n) | 太慢了 |
 | 最佳 | O(n3 log k) | O(n3 log k) | O(n²) | 已接受 |

 # 算法演练

 1. 构建邻接矩阵`A`。 对于每个有向边`u`到`v`， 放`A[u][v] = 1`。 该矩阵描述了图中移动的一步。 
2. 计算`A^k`使用二进制求幂。 如果当前位`k`设置后，将答案矩阵乘以当前的幂`A`。 然后方`A`为下一位准备矩阵。 这是可行的，因为每个整数幂都可以表示为 2 的幂的组合。 
3. 求幂完成后，将所得矩阵的每个元素相加。 每个条目代表一对有序顶点之间的行走次数，因此它们的总和就是行走总数。 

为什么它有效：关键的不变量是在处理一些位之后`k`，累积矩阵等于已从二进制表示中选择的两个的所有幂的乘积`k`。 矩阵乘法保留了路径计数的含义，因为组合两个矩阵会连接步行的两个连续部分。 因此，重复平方可创建路径长度矩阵`1, 2, 4, 8`依此类推，将所需的乘以精确给出长度矩阵`k`。 

# Python 解决方案```python
import sys

input = sys.stdin.readline

MOD = 10 ** 9 + 7

def multiply(a, b, n):
    res = [[0] * n for _ in range(n)]
    for i in range(n):
        for k in range(n):
            if a[i][k]:
                aik = a[i][k]
                for j in range(n):
                    res[i][j] = (res[i][j] + aik * b[k][j]) % MOD
    return res

def solve():
    n, m, k = map(int, input().split())

    mat = [[0] * n for _ in range(n)]
    for _ in range(m):
        a, b = map(int, input().split())
        mat[a - 1][b - 1] = 1

    ans = [[0] * n for _ in range(n)]
    for i in range(n):
        ans[i][i] = 1

    while k:
        if k & 1:
            ans = multiply(ans, mat, n)
        mat = multiply(mat, mat, n)
        k >>= 1

    result = 0
    for row in ans:
        result += sum(row)
        result %= MOD

    print(result)

if __name__ == "__main__":
    solve()
```邻接矩阵存储有表示起始顶点的行和表示结束顶点的列。 乘法函数遵循矩阵乘法的定义，其中选择中间顶点`k`意味着将步行分成两个连续的部分。 

单位矩阵用作初始答案，因为它代表乘法的中性元素。 如果二进制表示为`k`尚未包含任何已处理的位，尚未选择幂，因此累积的乘积必须作为恒等式开始。 

乘法例程跳过左侧矩阵中的零项。 由于许多图都是稀疏的，这可以避免实践中不必要的工作，同时保持所需的立方最坏情况。 Python 整数已经支持任意精度，但每个值都会减少模数`MOD`在乘法期间保持数字较小。

 | --- | --- | --- |
 | 时间 | O(n3 log k) | O(n3 log k) | 每个矩阵乘法的成本为 O(n3)，二进制求幂执行 O(log k) 乘法。 |

 # 边缘情况

 对于`k = 1`，算法不执行任何不必要的扩展。 二进制求幂立即使用原始邻接矩阵，并对所有条目进行求和，精确计算现有边。 输入时：```
3 2 1
1 2
2 3
```矩阵包含两个，所以输出是`2`。 

对于循环图，重新访问顶点是自然处理的，因为矩阵乘法计算转移而不存储访问的信息。 在：```
3 3 2
1 2
2 3
3 1
```平方矩阵包括三个可能的两条边游走。 阻止重新访问的图遍历将会错过所有这些。 

对于没有边的图：```
2 0 5
```邻接矩阵完全为零。 每次乘法都会使其为零，因此最终的总和也为零。 这避免了将顶点的存在视为暗示路径的存在。
