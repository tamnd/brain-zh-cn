 ## 解决方案
 ## 问题理解

 我们有一个 8 x 8 的棋盘，一个马放在左上角的方格上。 路径是一系列访问过的方格，其中每对连续的方格都通过合法的马移动连接。 马可以在从 0 到 任意次数的移动后停止。`k`，所以答案是该范围内每个长度的可能路径总数。 不同的移动选择会产生不同的路径，即使它们在同一个方块上结束。 答案必须以模数形式打印`2^32`。 

的价值`k`可以大到`10^9`，所以一一模拟动作是不可能的。 尽管棋盘很小，但可能的路径数量随着移动次数的增加而呈指数增长。 处理所有可能路径的解决方案将很快超出任何实际操作限制。 固定数量的小棋盘单元是我们可以利用的关键限制：只有 64 个可能的骑士位置，因此问题可以转化为固定大小状态空间上的操作。 

模数也很不寻常。 答案需要模数`2^32`，它自然适合无符号 32 位算术。 我们只需要保留每个中间值的最后 32 位。 在 Python 中，这意味着应用位掩码足以模拟所需的模数。 

一个常见的错误是忘记长度为零的路径是有效的。 例如，如果`k = 0`，骑士根本不动，但仍然存在一条仅由起始方格组成的路径。```
Input
0

Output
1
```另一个错误是只计算恰好之后的最终位置`k`移动。 该问题要求所有长度达到`k`。 为了`k = 1`，骑士可以留在原地或移动到角落的两个可到达的方格中的任何一个。```
Input
1

Output
3
```第三个问题是在边界附近构建骑士移动不正确。 马在棋盘中部最多有八种可能的走法，但在边缘附近则较少。 例如，最初的角方只有两次合法移动，而不是八次。 

## 方法

 直接的方法是运行深度优先搜索来生成每个可能的路径。 在深度为零时，我们计算当前路径，然后递归地尝试每个合法的骑士动作，直到我们使用过`k`移动。 此方法是正确的，因为它完全遵循有效路径的定义。 然而，它探索的是一棵分支树。 叶子的数量大致呈指数增长`k`，并且对于`k = 10^9`即使每平方移动几步也会使其完全无法使用。 

有用的观察是骑士没有任何记忆。 未来路径的数量仅取决于当前方格和剩余的移动次数。 由于只有 64 个方块，我们可以将整个过程表示为 64 个状态之间的转换。 

矩阵乘法可以一次对每个状态应用一个移动。 将转移矩阵提高到一个大幂可以让我们使用二进制求幂跳过数十亿次单独的移动。 我们还需要从零到的所有路径长度的总和`k`，不仅仅是精确之后的路径数`k`移动。 我们通过添加一个额外的状态来存储累积的答案来处理这个问题。 每个矩阵乘法执行一次骑士移动，并将当前路径数添加到累加器中。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数为`k`| O(k) 递归深度 | 太慢了 |
 | 最佳| O(65³ log k) | O(65³ log k) | O(65²) | 已接受 |

 ## 算法演练

 1. 给棋盘上的 64 个方格编号`0`到`63`。 构建转移矩阵`T`在哪里`T[i][j]`是`1`如果骑士可以从方格移动`i`到平方`j`， 和`0`否则。 这个矩阵准确地描述了马的一个动作。 
2. 添加表示累积答案的附加状态。 构造一个 65 x 65 矩阵`A`。 左上角的 64 x 64 块是骑士转移矩阵。 前 64 行的最后一列包含`1`，因为经过一次乘法之后，每条当前路径都会对答案做出一次贡献。 底行保持累加器不变。 
3. 从一个行向量开始，该行向量包含起始方格处的一条路径和答案值为`1`。 最初的答案是`1`因为包含了空路径。 
4. 应用后计算向量`A`确切地`k`使用二进制求幂的次数。 每个乘法代表一个可能的额外骑士动作。 
5. 从结果向量中读取累加器状态。 它包含长度为的所有路径计数的总和`0`通过`k`。 

增强状态起作用的原因是，在每次乘法之后，前 64 个值始终代表当前移动次数之后的路径。 额外的值存储所有先前层的总和。 由于每次转换都是线性的，因此矩阵运算在每一步之后都会保留这种关系。 

## 为什么它有效

 之后`i`乘法，向量的棋盘部分包含精确使用到达每个方格的方法数`i`骑士行动。 累加器包含长度为的路径总数`0`通过`i`。 

在下一次乘法期间，使用骑士转移矩阵对棋盘值进行转换，从而准确地生成长度为 的路径`i + 1`。 同时，累加器接收之前的板总数，这正是在该长度上添加的新路径的数量。 通过归纳法，经过`k`累加器相乘等于所需的总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1 << 32
SIZE = 65

def multiply(a, b):
    n = len(a)
    res = [[0] * n for _ in range(n)]
    for i in range(n):
        ai = a[i]
        ri = res[i]
        for k in range(n):
            if ai[k]:
                aik = ai[k]
                bk = b[k]
                for j in range(n):
                    ri[j] = (ri[j] + aik * bk[j]) & (MOD - 1)
    return res

def matrix_power(a, e):
    n = len(a)
    res = [[0] * n for _ in range(n)]
    for i in range(n):
        res[i][i] = 1
    while e:
        if e & 1:
            res = multiply(res, a)
        a = multiply(a, a)
        e >>= 1
    return res

def solve():
    k = int(input())

    moves = []
    for r in range(8):
        for c in range(8):
            cur = []
            for dr, dc in ((2, 1), (2, -1), (-2, 1), (-2, -1),
                           (1, 2), (1, -2), (-1, 2), (-1, -2)):
                nr = r + dr
                nc = c + dc
                if 0 <= nr < 8 and 0 <= nc < 8:
                    cur.append(nr * 8 + nc)
            moves.append(cur)

    a = [[0] * SIZE for _ in range(SIZE)]

    for i in range(64):
        for j in moves[i]:
            a[i][j] = 1
        a[i][64] = 1

    a[64][64] = 1

    p = matrix_power(a, k)

    start = [0] * SIZE
    start[0] = 1
    start[64] = 1

    ans = 0
    for i in range(SIZE):
        ans = (ans + start[i] * p[i][64]) & (MOD - 1)

    print(ans)

if __name__ == "__main__":
    solve()
```移动结构循环遍历每个方格并尝试八个可能的骑士方向。 无效坐标将被丢弃，这避免了对角和边的特殊处理。 

矩阵乘法函数使用位掩码而不是`% (2^32)`。 由于模数是 2 的幂，因此仅保留最低 32 位会得到完全相同的结果并且速度更快。 

求幂例程使用标准二进制分解`k`。 当一点点`k`设置后，矩阵的当前功率对最终结果有贡献。 单位矩阵表示零步。 

初始向量将一条路径放置在平方零上，并将一条路径放置在累加器中。 应用矩阵`k`次，因此累加器从空路径到所有路径中精确地收集每一层`k`移动。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(65³ log k) | O(65³ log k) | 65 x 65 矩阵大约需要 30 次矩阵乘法 |
 | 空间| O(65²) | 存储恒定数量的固定大小矩阵 |

 电路板尺寸永远不会改变，因此除了对数依赖之外，算法的尺寸实际上是恒定的`k`。 这就是为什么值大到`10^9`是可以管理的。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)

    def solve_local():
        k = int(sys.stdin.readline())
        MOD = 1 << 32
        SIZE = 65

        def multiply(a, b):
            n = len(a)
            res = [[0] * n for _ in range(n)]
            for i in range(n):
                for k in range(n):
                    if a[i][k]:
                        for j in range(n):
                            res[i][j] = (res[i][j] + a[i][k] * b[k][j]) & (MOD - 1)
            return res

        def power(a, e):
            n = len(a)
            r = [[0] * n for _ in range(n)]
            for i in range(n):
                r[i][i] = 1
            while e:
                if e & 1:
                    r = multiply(r, a)
                a = multiply(a, a)
                e >>= 1
            return r

        moves = []
        for r in range(8):
            for c in range(8):
                cur = []
                for dr, dc in ((2,1),(2,-1),(-2,1),(-2,-1),
                               (1,2),(1,-2),(-1,2),(-1,-2)):
                    nr, nc = r + dr, c + dc
                    if 0 <= nr < 8 and 0 <= nc < 8:
                        cur.append(nr * 8 + nc)
                moves.append(cur)

        a = [[0] * SIZE for _ in range(SIZE)]
        for i in range(64):
            for j in moves[i]:
                a[i][j] = 1
            a[i][64] = 1
        a[64][64] = 1

        p = power(a, k)

        v = [0] * SIZE
        v[0] = 1
        v[64] = 1

        ans = sum(v[i] * p[i][64] for i in range(SIZE)) & (MOD - 1)
        return str(ans)

    out = solve_local()
    sys.stdin = old
    return out

 ## 边缘情况

 对于`k = 0`，该算法从不乘以矩阵。 初始累加器已经包含一条路径，对应于停留在起始方格上的骑士。 

对于初始角正方形，转移矩阵仅包含两个出边。 移动生成在添加转换之前会检查棋盘限制，因此它不会意外地允许不可能的跳转到棋盘之外。 

对于非常大的`k`，该算法不会迭代移动。 相反，它会分解`k`转换为二进制幂并乘以矩阵约 30 次，因此即使移动次数为 10 亿，运行时间也保持稳定。
