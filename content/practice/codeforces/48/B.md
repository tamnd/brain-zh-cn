 ## 解决方案
 ## 问题理解

 花园被表示为`n × m`网格。 每个单元格包含`0`或者`1`。 一个`1`表示该正方形有一棵树，而`0`意味着广场是空的。 

我们想在网格内的某个地方放置一个矩形房屋地块。 矩形必须有尺寸`a × b`，但允许旋转，所以`b × a`矩形也是有效的。 所选矩形内的每棵树都会被删除。 任务是找到破坏树木最少的位置。 

这实际上是一个矩形查询问题。 对于每个有效的矩形位置，我们需要计算有多少个`1`s 位于其中，然后在所有位置中取最小值。 

限制很小：两个维度最多`50`。 一个网格最多包含`2500`细胞。 甚至一个`O(n^2 m^2)`解决方案在这里完全没问题，因为`50^4 = 6.25 million`，这完全在 Python 的时间限制之内。 

危险的部分不是性能，而是矩形放置和旋转的正确性。 

一个容易犯的错误就是忘记房子可以轮换。 

例如：```
2 3
1 1 1
0 0 0
3 2
```长方形`3 × 2`不直接适合，因为`3 > n`，但是旋转后的`2 × 3`矩形完美契合。 正确答案是：```
3
```粗心的实现仅检查一个方向会错误地拒绝放置。 

另一个常见的错误是枚举左上角时出现相差一错误。 

考虑：```
3 3
0 0 0
0 1 0
0 0 0
2 2
```有效的左上角是`(0,0)`,`(0,1)`,`(1,0)`， 和`(1,1)`。 在迭代过程中缺少最后一行或最后一列可能会跳过有效的最佳矩形。 

正确答案是：```
0
```因为我们可以将矩形放置在远离中心树的任何角落。 

还有一种特殊情况，即矩形大小等于整个网格。 

例子：```
2 2
1 0
1 1
2 2
```仅存在一个位置，因此答案必须等于树的总数：```
3
```假设总是有空间滑动矩形的实现在这里会失败。 

## 方法

 最直接的解决办法就是暴力破解。 

对于矩形的每个有效位置，我们扫描该矩形内的每个单元格并计算它包含多少棵树。 由于允许旋转，我们对两者重复此操作`(a, b)`和`(b, a)`。 

假设矩形大小为`h × w`。 大致有`(n - h + 1)(m - w + 1)`展示位置。 对于每个展示位置，我们都会检查`h × w`细胞。 

总复杂度变为：```
O((n - h + 1)(m - w + 1)hw)
```在最坏的情况下，每个数量都在`50`，所以操作次数大致为：```
50 × 50 × 50 × 50 = 6.25 million
```即使是这种蛮力解决方案实际上也能在给定的约束下通过。 

尽管如此，还是有一种更清晰的方式来思考这个问题。 每个查询都要求子矩形内的值的总和。 逐个单元地重新计算该总和会不必要地重复工作。 

关键的观察结果是，可以使用 2D 前缀和立即回答矩形和。 

我们构建一个前缀矩阵，其中：```
pref[i][j]
```存储矩形内的树数`(1,1)`到`(i,j)`。 

然后可以在常数时间内通过包含-排除计算任意矩形和。 

蛮力的想法仍然保持不变：枚举所有可能的位置。 改进来自于将内部矩形扫描替换为`O(1)`询问。 

这将复杂性降低到：```
O(number of placements)
```这最多是关于`2500`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nmab) | O(1) | O(1) | 已接受 |
 | 最佳| O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 1. 读取网格并将其存储为整数。 
2.构建2D前缀和数组`pref`。`pref[i][j]`存储矩形内从左上角开始的树总数`(1,1)`到`(i,j)`。 
3. 定义一个辅助函数，使用包含-排除返回任意矩形内的树数。 

对于有角的矩形`(r1,c1)`和`(r2,c2)`：```
sum =
pref[r2][c2]
- pref[r1-1][c2]
- pref[r2][c1-1]
+ pref[r1-1][c1-1]
```4. 尝试两个方向：`(a,b)`和`(b,a)`。 

允许旋转，因此必须单独检查两个尺寸。 
5. 对于每个方向，枚举每个有效的左上角。 

如果矩形尺寸为`h × w`， 然后：```
1 ≤ row ≤ n-h+1
1 ≤ col ≤ m-w+1
```6. 对于每个放置，使用前缀和计算矩形内树的数量。 
7. 保留所有展示位置的最小值并打印它。 

### 为什么它有效

 前缀和矩阵保证每个矩形和通过包含-排除恰好计算一次。 检查每个有效的矩形放置，包括两个允许的方向。 由于该算法会检查所有候选树并计算每个候选树中树的确切数量，因此找到的最小值必然是最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

grid = [list(map(int, input().split())) for _ in range(n)]

a, b = map(int, input().split())

pref = [[0] * (m + 1) for _ in range(n + 1)]

for i in range(1, n + 1):
    for j in range(1, m + 1):
        pref[i][j] = (
            grid[i - 1][j - 1]
            + pref[i - 1][j]
            + pref[i][j - 1]
            - pref[i - 1][j - 1]
        )

def rect_sum(r1, c1, r2, c2):
    return (
        pref[r2][c2]
        - pref[r1 - 1][c2]
        - pref[r2][c1 - 1]
        + pref[r1 - 1][c1 - 1]
    )

ans = float('inf')

for h, w in [(a, b), (b, a)]:
    if h > n or w > m:
        continue

    for r in range(1, n - h + 2):
        for c in range(1, m - w + 2):
            trees = rect_sum(r, c, r + h - 1, c + w - 1)
            ans = min(ans, trees)

print(ans)
```第一部分读取网格并构建前缀和矩阵。 该实现使用从 1 开始的索引`pref`，这消除了许多边界检查。 每个前缀条目包括当前单元格、上面的矩形、左边的矩形，并减去一次重叠。 

这`rect_sum`功能是核心效用。 它使用包含-排除在恒定时间内计算任何矩形总和。 坐标是包含在内的，这就是为什么右下角被传递为`r + h - 1`和`c + w - 1`。 

外循环检查矩形的两个方向。 如果一个方向不适合网格，则会立即跳过它。 

范围：```
range(1, n - h + 2)
```和```
range(1, m - w + 2)
```都是容易犯错误的地方。 Python 范围不包括端点，所以`+2`必须包含最后一个有效的起始位置。 

答案将根据遇到的最小矩形和进行更新。

 考虑仅旋转的情况：```

1 1 1
0 0 0
