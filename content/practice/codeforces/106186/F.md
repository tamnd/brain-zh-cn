 ## 解决方案
 ## 问题理解

 我们得到了以下数字的排列`1`到`n`。 任务是计算索引的有序选择`i`和另一个索引`j`值在哪里`j`可以用作跳跃长度，并且在从`i`，那里找到的值恰好是起始值和跳跃长度的总和。 

换句话说，如果位置上的值`j`是`x`，我们需要：`a[i + x] = a[i] + x`位置`i + x`必须存在于数组内部。 答案是这样的有效选择的数量`i`和`j`。 

排列属性是关键的限制。 每个数字都来自`1`到`n`只出现一次，因此每个可能的跳跃长度`x`恰好有一个它发生的位置。 

和`n`最多`200000`，检查每对索引将需要大约`n² / 2`，在最坏的情况下大约有 200 亿张支票。 这远远超出了典型的竞争性编程时间限制所允许的范围。 我们需要将条件转换为可以在线性时间内计数的东西。 

主要的边缘情况来自这样一个事实：转换后的视图中的有效对不一定是与以下相同的索引对：`(i, j)`从声明中。 

例如：```
5
3 4 1 2 5
```有效答案是`2`。 一对有效的原始对是`(3, 3)`， 因为`a[3] = 1`和`a[4] = 2`, 给予`1 + 1 = 2`。 如果粗心的解决方案只检查具有不同索引的对，就会错过这种情况。 

另一种边缘情况是许多索引具有相同的转换值。 例如：```
4
1 2 3 4
```答案是`6`。 每对都有效，因为数组正好增加 1，因此所有索引都具有相同的值`index - value`。 仅计算相邻位置会错误地返回较小的答案。 

## 方法

 直接解遵循定义。 对于每一个可能的索引对`(i, j)`，我们计算跳跃长度`a[j]`，检查是否`i + a[j]`位于数组内部，并比较`a[i + a[j]]`和`a[i] + a[j]`。 

这是正确的，因为它完全测试了所需的条件。 然而，有`n²`可能的有序对。 什么时候`n = 200000`，这会产生大约四百亿次操作，这是不可能的。 

有用的观察来自于重写方程。 让：```
x = a[j]
q = i + x
```条件变为：```
a[q] = a[i] + x
```自从`q - i = x`，我们得到：```
a[q] - a[i] = q - i
```重新排列：```
q - a[q] = i - a[i]
```因此，我们不需要寻找特殊的跳跃值，而只需要计算具有相同值的位置对`index - value`。 

具有相同变换值的每一对位置恰好对应于一个有效的原始对。 如果持仓`p < q`满足：```
p - a[p] = q - a[q]
```然后：```
a[q] - a[p] = q - p
```距离`q - p`是一个介于`1`和`n`，并且因为该数组是一个排列，所以该数字出现在某处`a[j]`。 选择那个`j`给出所需的原始对。 

问题简化为对相等的值进行分组`index - value`并添加每组内的对数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 按索引值差异分组 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 迭代每个位置`i`并计算值`i - a[i]`。 我们使用基于一的索引，因为语句以这种方式描述位置。 
2. 存储每个变换后的值出现的次数。 具有相同变换值的位置可以彼此形成有效对。 
3. 当变换后的值已经出现时`cnt`次，我们再次看到它，新的位置形成`cnt`新对。 添加`cnt`在增加频率之前先找到答案。 
4. Output the accumulated count.

 计数起作用的原因是，当从左到右处理位置时，相同转换值的每个先前出现都是较早的索引，与当前索引形成有效对。 

为什么它有效：

 转换完全保留了所需的条件。 有效的原始对产生两个位置`i`和`i + a[j]`其值满足相等`index - value`。 反之，任意两个位置相等`index - value`距离等于它们的值差，并且该距离以某个数组值的形式出现，因为该数组是一个排列。 因此，每一对计数都对应于原始问题中的一个且仅有一个有效选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    freq = {}
    ans = 0

    for i, x in enumerate(a, start=1):
        key = i - x
        ans += freq.get(key, 0)
        freq[key] = freq.get(key, 0) + 1

    print(ans)

if __name__ == "__main__":
    solve()
```该循环通过开始使用基于一的位置`enumerate`从`1`。 这避免了从零开始的 Python 索引和问题的数学位置之间的转换。`freq`存储每个值为 的先前位置的数量`i - a[i]`。 当相同的值再次出现时，之前的每一次出现都会创建一个新的有效对，因此我们在插入当前位置之前添加当前频率。 

Python 整数是任意精度的，因此即使对的数量可以超过 32 位整数限制，答案也不需要特殊处理。 

实现中没有边界检查，因为代数变换已经包含跳转保持在数组内部的条件。 每个计数对的第二个位置是排列中的真实位置。 

## 工作示例

 考虑：```
5
3 4 1 2 5
```转换后的值为：

 | 职位| 价值| 位置-价值| 当前答案 |
 | ---| ---| ---| ---|
 | 1 | 3 | -2 | 0 |
 | 2 | 4 | -2 | 1 |
 | 3 | 1 | 2 | 1 |
 | 4 | 2 | 2 | 2 |
 | 5 | 5 | 0 | 2 |

 这些组是`{-2: 2}`,`{2: 2}`， 和`{0: 1}`。 大小为 2 的两组各贡献一对，给出最终答案`2`。 

该轨迹表明该算法不需要知道哪个位置包含跳跃长度。 排列属性自动处理该连接。 

现在考虑：```
4
1 2 3 4
```| 职位| 价值| 位置-价值| 当前答案 |
 | ---| ---| ---| ---|
 | 1 | 1 | 0 | 0 |
 | 2 | 2 | 0 | 1 |
 | 3 | 3 | 0 | 3 |
 | 4 | 4 | 0 | 6 |

 所有位置共享相同的转换值，因此每一对都被计算在内。 结果是`4 * 3 / 2 = 6`。 

此示例验证该解决方案是否可以正确处理大型组，而不是仅检查附近的位置。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个数组元素都会处理一次，每个字典操作的时间复杂度预计为 O(1)。 |

 ## 边缘情况

 对于这个案例：```
5
3 4 1 2 5
```该算法计算变换后的值：```
-2, -2, 2, 2, 0
```重复的值创建两对。 这些对应于两个有效的原始选择，包括使用相同索引作为原始对的两个部分的情况。 

为了：```
4
1 2 3 4
```所有变换后的值均为零。 该算法不断添加先前出现的次数，产生：```
0 + 1 + 2 + 3 = 6
```它对每个可能的对恰好计数一次。 

对于没有重复变换值的排列，每个频率都保持为 1，因此答案保持为零。 这种情况很自然地得到处理，因为先前的位置无法与当前的位置匹配。
