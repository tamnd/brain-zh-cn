 ## 解决方案
 ## 问题理解

 我们得到一个加权无向图，其中节点的子集是“中心”，这意味着每当机器人到达那里时，它的电池就会立即充满。 机器人启动并必须在中心节点完成每个查询。 每条边都有一个权重，穿过它会消耗同样多的能量。 机器人无法穿过边缘，除非其当前能量至少为边缘权重。 

问题在于电池容量不固定。 对于每个查询，我们都会被问到：如果机器人在一个中心开始充满电并想要到达另一个中心，那么最小可能的电池容量是多少，以便存在一些步行（不一定简单），允许到达目的地，尊重能量限制和中心的充电行为？ 

重要的结构细节是机器人可以重新访问节点和边缘，但只有中心重置其能量。 非中心节点只是中间状态，没有充值作用。 

约束足够大，以至于原始图上的任何每个查询最短路径都太慢。 由于有多达 300,000 个边和查询，即使每个查询只有一个 Dijkstra 也是不可能的。 任何尝试在节点上显式模拟能量的解决方案都会爆炸，因为状态空间将变成“（节点，剩余能量）”，这太大了。 

一个不太明显的困难是路径可以在多个点“重置”能量，这意味着有效成本并不是通常意义上的沿单个路径的累加。 原始图中中心之间的最短路径并不能直接捕获约束，因为如果将长路径分成多个段，其中每个段的最大边缘权重受电池容量限制，则长路径可能是可行的。 

打破天真的思维的边缘情况包括这样的情况：最佳路线使用绕行多个中心来避免单个重型边缘。 例如，如果两个中心之间的直接路径包含权重为 100 的边，但存在一条通过中间中心的较长路线，其中每条边≤ 20，则容量 20 就足够了，即使最短路径包含巨大的边。 这表明我们正在优化瓶颈约束，而不是总重量。 

另一种失败情况是假设我们只需要原始图中某些路径上的最大边。 这也是错误的，因为充值点重置了约束，因此我们可以将多个“本地可行”片段缝合在一起。 

## 方法

 蛮力的想法是修复容量`c`并检查两个中心之间是否存在路径。 这成为一个可达性问题，只有当边的权重≤当前能量时我们才能遍历边，并且能量在中心重置。 为了模拟这一点，我们需要在扩展状态上使用状态 BFS 或 Dijkstra`(node, energy)`，或者我们会尝试贪婪地模拟路径。 无论哪种方式，一次可行性检查大致是`O(m log n)`或者更糟。 

由于每个查询都需要二进制搜索`c`，而且每次检查都很昂贵，我们很快就会超出限制。 和`q = 3e5`， 甚至`O(m)`每张支票已经太大了。 

关键的观察结果是电池约束仅关心两个充电点之间使用的最大边缘权重。 一旦我们确定了容量`c`，我们实际上只能遍历权重 ≤ 的边`c`，但有了额外的自由，我们可以在中央的能量重置方面进行“传送”。 这将图变成了一种结构，在过滤边之后，只有中心之间的连接才重要。 

这建议颠倒这个过程：我们不是独立回答查询，而是按权重对所有边进行排序并逐步激活它们。 我们想知道，对于每对中心点，最小阈值`c`他们在这种“充电感知连接”下建立连接。 

这正是图上的动态连接问题，其中边按权重递增的顺序添加。 我们维护中心之间的连接，但连接并不是仅在节点上的标准 DSU，因为非中心可以连接路径而不是端点。 标准技巧是处理所有节点，但一旦边缘被激活，DSU 连接就会自动捕获可达性。 充电约束是隐式处理的，因为一旦所有边 ≤ c 都存在，任何停留在这些边内的行走都是有效的：中心之间的每个段将具有最大边 ≤ c，并且充电允许跨段继续。 

因此，对于固定阈值，边 ≤ c 的子图中的连通性是充分且必要的。 因此，我们可以在边缘上构建类似 Kruskal 的结构并维护 DSU。 当两个中心连接起来时，沿其 DSU 合并路径使用的最大边正是该对的答案。 我们使用按大小并集的 DSU 来存储此数据，并通过跟踪何时发生合并来增强，通常通过构建 Kruskal 重建树或使用 DSU 记录合并权重然后回答 LCA 查询来解决。 

更精细的观点是我们在图上构造一个最小生成树。 在MST上，两个节点之间的唯一路径上的最大边在原始图中的所有可能路径中被最小化。 由于我们的可行性条件正是关于最小化沿某些带有重置的有效行走所需的最大边缘容量，因此 MST 路径最大值给出了答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（模拟每个查询）| O(q·m) 或更差 | O(n + m) | 太慢了|
 | 最优（Kruskal + LCA / DSU 重建）| O(m log m + q log n) | O(m log m + q log n) | O(n + m) | 已接受 |

 ## 算法演练

 我们通过将其简化为回答最小生成树上的最大路径边查询来解决该问题。 

1. 按权重以非降序对所有边进行排序。 这确保我们首先考虑尽可能小的瓶颈，因此连接性是按照可行性递增的顺序构建的。 
2. 运行 Kruskal 算法构建最小生成树（或森林，但图是相连的，因此它成为一棵树）。 每次合并两个组件时，我们都会在重建树中创建一个父节点，其边权重等于合并边。 
3. 构建基于 DSU 的重建树，其中原始节点是叶子，每个并集创建一个代表合并组件的新内部节点。 存储在该内部节点的权重是导致合并的边权重。 该结构对阈值增加时连通性出现的顺序进行编码。 
4. 在此重建树上预先计算 LCA。 对于每个节点，我们存储其深度和二元提升父节点，以及从该节点到其祖先的最大边权重。 
5. 对于每个查询 (a, b)，计算它们在重建树中的 LCA。 答案是这棵树中从a到b的路径上的最大边权重，它对应于在该过程下使它们连接所需的最小容量。 

之所以有效，是因为 Kruskal 的构造确保两个节点第一次连接时，所使用的边在所有可能的连接中具有尽可能小的最大权重。 重建树精确地编码了组件合并的阈值，因此 LCA 捕获了两个中心的最早合并点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1]*n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]
        return True

def solve():
    n, m, k, q = map(int, input().split())
    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((w, u-1, v-1))

    edges.sort()

    # build Kruskal reconstruction tree
    N = 2*n
    dsu = DSU(N)
    tree = [[] for _ in range(N)]
    val = [0]*N
    ptr = n

    for w, u, v in edges:
        if dsu.union(u, v):
            ru = dsu.find(u)
            rv = dsu.find(v)
            new = ptr
            ptr += 1
            val[new] = w
            tree[new].append(ru)
            tree[new].append(rv)
            dsu.p[ru] = new
            dsu.p[rv] = new

    root = ptr - 1

    LOG = 20
    up = [[-1]*N for _ in range(LOG)]
    mx = [[0]*N for _ in range(LOG)]
    depth = [0]*N

    # build parent pointers
    order = list(range(ptr))
    for v in range(ptr):
        for to in tree[v]:
            up[0][to] = v
            mx[0][to] = val[v]
            depth[to] = depth[v] + 1

    for j in range(1, LOG):
        for v in range(ptr):
            if up[j-1][v] != -1:
                up[j][v] = up[j-1][up[j-1][v]]
                mx[j][v] = max(mx[j-1][v], mx[j-1][up[j-1][v]])

    def get(u, v):
        if depth[u] < depth[v]:
            u, v = v, u
        ans = 0
        diff = depth[u] - depth[v]
        for i in range(LOG):
            if diff >> i & 1:
                ans = max(ans, mx[i][u])
                u = up[i][u]
        if u == v:
            return ans
        for i in reversed(range(LOG)):
            if up[i][u] != up[i][v]:
                ans = max(ans, mx[i][u], mx[i][v])
                u = up[i][u]
                v = up[i][v]
        ans = max(ans, mx[0][u], mx[0][v])
        return ans

    for _ in range(q):
        a, b = map(int, input().split())
        print(get(a-1, b-1))

solve()
```DSU 构建一个层次结构，其中每个联合引入一个新节点，代表两个组件首次连接的时刻。 该节点存储的值是负责该合并的边权重，这正是该连接事件的阈值成本。 

二进制提升表存储沿祖先跳跃的最大边缘权重，因此查询减少为计算重建树中两个中心之间的路径上的最大合并权重。 

一个微妙的点是，原始节点是这棵树中的叶子，因此它们自然地参与 LCA 查询，无需特殊处理。 另一个细节是，我们必须通过在每个并集之后链接 DSU 代表来确保重建树正确构建，否则父子关系会变得不一致。 

## 工作示例

 ### 示例 1

 我们考虑一个中心分散的小链，并查询其中两个之间的连接性。 

| 步骤| 行动| DSU 状态 | 键合并权重 |
 | ---| ---| ---| ---|
 | 1 | 首先处理最小的边缘 | 组件逐渐融合| 2 |
 | 2 | 继续克鲁斯卡尔 | 更大的组件形式| 4 |
 | 3 | 合并达到中央连接 | 树节点已创建| 8 |

 两个查询中心之间的 LCA 位于引入边权重 12 时创建的节点，因此答案变为 12。 

该跟踪表明，答案是由两个包含中心的组件在 Kruskal 过程中第一次合并确定的，而不是由原始图中的任何直接路径确定的。

 我们绘制了一张图表，其中存在多个替代路线。 

| 步骤| 行动| DSU 状态 | 键合并权重 |
 | ---| ---| ---| ---|
 | 1 | 添加浅色边缘 | 小簇形成| 5 |

 | 3 | 直接重边存在但未使用 | 在 MST 中被忽略 | 38 | 38

 重建树确保节点之间的路径使用尽可能小的瓶颈，确认即使存在较重的直接边，如果存在较轻的连接结构也不会影响答案。

 ## 边缘情况

 关键的边缘情况是两个中心之间的直接边缘非常大，但完全通过小边缘存在间接路径。 例如，如果节点 1 和 2 是中心，并且存在权重 1000 的边 (1,2)，而且还有权重 2 和 3 的路径 1-3-4-2，则正确答案为 3。重建树确保 MST 中永远不会选择权重 1000 的边，因此基于 LCA 的答案正确地忽略它。 

另一种边缘情况是多个等权重边缘以不同顺序连接组件。 Kruskal 可以选择其中的任何一个，但由于它们都具有相同的权重，因此重建树节点仍然具有相同的值，因此最大路径查询保持稳定。 

第三种情况是线性图，其中中心位于端点。 答案只是链上的最大边，LCA 精确地减少到最大合并权重，确认重建树的行为就像原始路径结构的压缩版本。
