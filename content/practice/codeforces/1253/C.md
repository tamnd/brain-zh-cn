 ## 解决方案
 ## 问题理解

 我们得到了一个糖果列表，每个糖果都有一个代表其甜度的正整数值。 小优想吃东西$k$每人一份糖果$k$从 1 到$n$。 然而，她不能吃超过$m$一天之内就能吃到甜食。 

时间从第一天开始分为几天。如果当天吃了甜食$d$，其对总惩罚的贡献为$d \cdot a_i$，因此延迟消耗会随时间线性增加成本。 每种糖果必须只吃一次或根本不吃。 

对于每一个$k$，如果 Yui 选择任何一个，我们希望总惩罚尽可能最小$k$糖果并在最多的约束下以最佳方式安排它们$m$每天可以吃甜食。 

关键的交互是排序和分组之间的。 选择吃哪种糖果还不够；还需要注意。 它们在几天内的分布方式决定了应用于每个值的乘数。 

约束条件很大：最多$2 \cdot 10^5$糖果。 任何试图为每个独立地重新计算最佳调度的解决方案$k$或者天真地模拟日常的贪婪决策会太慢。 一个$O(n^2)$甚至$O(n^2 \log n)$方法不会通过。 我们应该期待接近的东西$O(n \log n)$或者$O(n)$排序后。 

当贪婪策略试图总是获取最小的可用糖果而不考虑批量效应时，就会出现微妙的失败情况。 例如，如果$m = 2$和价值观是$[1, 100, 101]$，按到达顺序挑选糖果会导致几天内的错误配对和过度惩罚。 正确的策略可能会延迟选择或以不同的方式对选择进行分组，以防止过早地将大值乘以大日指数。 

## 方法

 如果我们修复一个子集$k$糖果，剩下的唯一决定是如何在几天内分配它们，每天最多持有$m$项目。 蛮力方法会尝试大小的所有子集$k$，并为每个子集计算最佳调度。 即使贪婪地进行调度，枚举子集也会产生成本$\binom{n}{k}$，即使对于小规模来说也是不可行的$n$。 

一个更有用的观点是按价值对糖果进行排序。 假设我们决定采取$k$最小的糖果。 这对于固定$k$因为惩罚是线性的$a_i$，并且在任何计划下，较大的值总是更昂贵。 

现在问题减少到订购这些$k$随着时间的推移选择的值。 最好的策略是始终在早期放置较大的值，因为早期的乘数较小。 由于每天最多可以花费$m$糖果，结构变成：我们在第一天填充最多$m$最小的选定糖果，然后是第二天的下一批，依此类推。 

这建议按排序顺序处理糖果并将它们分组为大小块$m$。 每个区块对应一天，区块中的所有元素$d$得到乘数$d$。 

然后，我们维护前缀累积：排序后，我们可以增量计算贡献，更新所有的答案$k$同时通过扩展当前的区块结构。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 太慢了|
 | 最优（排序+批量累加）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们首先按照甜度非递减顺序对所有糖果进行排序。 这确保了当我们获取该数组的前缀时，我们始终为任何固定选择最佳可能的集合$k$。 

我们模拟为所有人构建答案$k$立即：

 1. 数组排序$a$按递增顺序。 这可确保较早分配较小的值。 
2. 维护当日块内的值的运行总和以及初始化为零的全局答案数组。 
3. 迭代排序的糖果，跟踪它们的位置。 
4. 对于位置处的每个元素$i$，确定其日指数为$\lfloor i / m \rfloor + 1$。 
5. 将其贡献添加到运行总计中，因为它会影响所有后缀答案$x_k$在哪里$k \ge i+1$。 
6. 逐步累积答案：每个前缀定义了一个候选解决方案，用于准确选择那么多糖果。 
7. 输出结果数组。 

更准确的理解方式是，每个元素都对所有元素做出贡献$k$它包含在哪里，其乘数仅取决于有多少个完整的块大小$m$按排序顺序位于它之前。 

它为何有效与交换论点有关。 如果两种糖果的价值不符，但前后放置的顺序不一致，则交换它们以使较大的价值获得较小的乘数总是会降低或保持总成本。 在每一天内，排序并不重要，但在几天内，单调性迫使按排序顺序分组。 因此，最佳结构是通过分批大小的排序和填充来唯一确定的$m$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort()
    
    res = [0] * n
    
    current_sum = 0
    day_cost = 0
    j = 0
    
    for i in range(n):
        day = i // m + 1
        current_sum += a[i] * day
        res[i] = current_sum
    
    print(*res)

if __name__ == "__main__":
    solve()
```该实现依赖于排序来强制执行正确的全局结构。 关键的观察是，一旦排序，最佳调度就由大小的块隐式确定$m$，因此除了将乘数计算为指数函数之外，我们从未明确模拟天数。 

数组`res[i]`表示精确获取的最小成本$i+1$糖果，因为长度前缀$i+1$总是最优的。 运行总和通过整数除以 (m`.

 一个常见的错误是尝试分别重新计算每天的总和，这会导致重复$O(n^2)$积累。 在这里，一切都一次性摊销。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    a = list(map(int, input().split()))

    res = []
    for i in range(n):

        if i == 0:

 ## 边缘情况

 当$m = 1$，每一个糖果都去新的一天，所以惩罚就变成了排序后前缀和的总和。 该算法自然地处理这个问题，因为每个索引形成自己的块，并且乘数等于位置。 

什么时候$m \ge n$，所有糖果都在第一天吃掉，所以答案只是排序数组的前缀和，无需缩放。 由于整数除法得出所有指数的第 1 天，因此计算可以正确减少。 

当所有值都相等时，原则上任何排序都是最优的，但批处理仍然会产生不断增加的乘数。 该算法分配较晚的糖果较大的日指数（由于容量限制，这是不可避免的），并匹配最小可实现的总数。
