 ## 解决方案
 ## 问题理解

 我们收到一部带有已安装应用程序列表的手机。 每个应用程序都会消耗一定量的内存，并且如果我们删除它，还会有一个以便利性损失来衡量的“成本”。 每个应用程序都会贡献 1 或 2 个便利点。 

任务是删除应用程序的子集，以便释放的总内存至少达到所需的阈值$m$，同时最大限度地减少总体便利性损失。 如果无法释放足够的内存，我们必须报告这一事实。 

因此，输入为我们提供了两个并行数组：一个描述内存大小，一个描述每个应用程序的“重要性”。 我们正在选择一个满足总大小的背包式约束的子集，但成本非常简单，因为它只需要两个可能的值。 

塑造解决方案的关键约束是所有测试用例中的应用程序总数，最多为$2 \cdot 10^5$。 这立即排除了尝试所有子集或对内存值使用二次动态规划的任何解决方案。 满满一背包$m$也是不可能的，因为$m$可以达到$10^9$。 

一种常见的失败模式来自于将其视为标准背包或贪婪比率问题。 例如，选择具有最佳内存成本比的应用程序可能会失败：

 输入：```
3 10
6 5 4
2 1 1
```贪婪比率可能会选择 (6,2) 和 (5,1) 作为总内存 11 成本 3。但最佳也是 (6,2)+(4,1)=10 成本 3，因此平局可以隐藏错误； 更糟糕的例子是贪婪失败，因为成本只有 1 或 2，而不是连续的。 

另一个微妙的边缘情况是，最佳解决方案使用许多低成本应用程序 (b = 1)，但天真的方法首先耗尽 b = 2 个应用程序并过早停止。 

成本结构只有 1 或 2，这使得问题变得容易处理。 

## 方法

 暴力方法将枚举应用程序的所有子集，计算总内存和总成本，并采用最佳有效子集。 这在概念上是有效的，因为每个子集都会被检查，但它需要$2^n$评估，即使对于$n = 40$。 

更结构化的暴力是使用递归或 DP 索引和内存总和来尝试所有子集，但内存维度最多为$10^9$，使得任何DP状态空间立即爆炸。 

关键的观察结果是成本是二元的：每个应用程序都属于两个组之一。 这建议根据应用程序的成本将应用程序分为两个列表。 如果我们按内存降序对每组中的应用程序进行排序，则任何最佳解决方案都将从成本 1 组和成本 2 组中获取一些最大内存项目。 

然而，单独选择它们是不够的，因为权衡是全局性的：有时，如果释放更多内存，采用稍小的 cost-2 应用程序会更好。 

关键的见解是按内存降序对所有应用程序进行排序，但以允许增量选择我们包含的成本 2 应用程序数量的方式处理它们。 排序后，我们预先计算两组的内存前缀和。 然后我们尝试所有可能的计数，选择​​最好的$k$cost-2 应用程序，并使用 cost-1 应用程序满足剩余内存需求。 

这将问题简化为将两个排序序列与前缀和组合，而不是搜索子集。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n)$|$O(n)$| 太慢了|
 | 最优（排序+贪心+前缀和）|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将应用程序分为两组：成本为 1 的应用程序和成本为 2 的应用程序。 

1. 根据成本将所有应用程序分成两个列表。 这隔离了我们将相互权衡的两个“定价层”。 
2. 按内存大小的降序对两个列表进行排序。 这确保了每当我们采取$k$从一组应用程序中，我们总是选择在内存增益方面最有效的应用程序。 
3. 为两个组构建前缀和数组。 索引处的前缀和$i$给出通过采用最佳值可获得的最大内存$i$该类型的应用程序。 
4. 计算总可用内存。 如果即使拿走所有应用程序还不够，则立即输出-1。 
5. 对于每个可能的数字$i$使用 cost-2 应用程序（从 0 到 len(b2)），计算获得的内存。 如果已经达到$m$, 记录成本$2i$。 
6. 如果不够，请计算所需的剩余内存，并使用前缀和上的二分搜索来确定需要多少个 cost-1 应用程序。 
7. 跟踪所有有效拆分的最小总成本。 

这样做的原因是成本为 2 的应用程序在成本上确实更差，但每个项目的内存可能更好，因此唯一有意义的决定是包含多少个应用程序。 一旦修复，其余部分就会减少为来自 cost-1 应用程序的单一贪婪填充。 

### 为什么它有效

 任何最佳解决方案都可以重新排列，以便在每个成本组中，所选应用程序都是具有最大内存的应用程序。 如果解决方案使用较小内存的应用程序，而同一组中未使用较大内存的应用程序，则交换可以在不增加成本的情况下提高或保留可行性。 此交换参数可确保仅考虑每个组内的前缀选择不会错过最佳配置。 一旦两个组都减少为前缀选择，唯一剩下的自由度就是从 cost-2 组中取出多少项。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        ones = []
        twos = []
        
        total = 0
        
        for ai, bi in zip(a, b):
            total += ai
            if bi == 1:
                ones.append(ai)
            else:
                twos.append(ai)
        
        if total < m:
            print(-1)
            continue
        
        ones.sort(reverse=True)
        twos.sort(reverse=True)
        
        pre1 = [0]
        for x in ones:
            pre1.append(pre1[-1] + x)
        
        pre2 = [0]
        for x in twos:
            pre2.append(pre2[-1] + x)
        
        ans = float('inf')
        
        j = len(ones)
        
        for i in range(len(twos) + 1):
            mem2 = pre2[i]
            cost = 2 * i
            
            if mem2 >= m:
                ans = min(ans, cost)
                continue
            
            need = m - mem2
            
            # smallest j such that pre1[j] >= need
            l, r = 0, len(ones)
            while l <= r:
                mid = (l + r) // 2
                if pre1[mid] >= need:
                    j = mid
                    r = mid - 1
                else:
                    l = mid + 1
            
            if pre1[j] >= need:
                ans = min(ans, cost + j)
        
        print(ans if ans != float('inf') else -1)

if __name__ == "__main__":
    solve()
```该实现首先将应用程序划分为两个数组并对每个数组进行排序。 前缀和允许从每组中获取固定数量的恒定时间评估。 在确定成本 2 应用程序的选择后，二分搜索会找到所需的成本 1 应用程序的最小数量。 这避免了重复地重新计算总和，并使第二组的每次迭代的解决方案保持在对数时间内。 

一个微妙的点是，我们必须为每个 cost-2 计数选择重新计算二分搜索，因为剩余的要求发生了变化。 另一个重要的细节是处理仅成本 2 应用程序就已经满足要求的情况。 

## 工作示例

 ### 示例 1

 输入：```
n=5, m=7
a=[5,3,2,1,4]
b=[2,1,1,2,1]
```我们分开：

 | 集团| 价值观 |
 | ---| ---|
 | 成本 1 | [3,2,4]|
 | 成本 2 | [5,1]|

 排序：

 成本 1 → [4,3,2]

 成本 2 → [5,1]

 前缀和：

 成本 1：[0,4,7,9]

 成本 2：[0,5,6]

 我们尝试选择：

 | 成本2计数| 记忆2 | 剩余| 最佳成本1 | 总成本|
 | ---| ---| ---| ---| ---|
 | 0 | 0 | 7 | 2（3+4）| 2 |
 | 1 | 5 | 2 | 1 | 3 |
 | 2 | 6 | 1 | 0 | 4 |

 最小值为 2。 

这证实完全跳过昂贵的 cost-2 应用程序可能是最佳选择。 

### 示例 2

 输入：```
n=4, m=10
a=[5,1,3,4]
b=[1,2,1,2]
```成本 1：[5,3]

 成本 2：[4,1]

 前缀和：

 成本 1：[0,5,8]

 成本 2：[0,4,5]

 尝试：

 | 成本2 | 记忆2 | 剩余| 需要成本1 | 总计 |
 | ---| ---| ---| ---| ---|
 | 0 | 0 | 10 | 10 不可能| 信息 |
 | 1 | 4 | 6 | 2 | 4 |
 | 2 | 5 | 5 | 1 | 5 |

 最好是4。 

这显示了采用更多成本 2 项目与依赖成本 1 重量级项目之间的权衡。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(n \log n)$| 排序占主导地位； 每个测试还对 cost-2 项目进行线性扫描，并使用二分搜索对 cost-1 前缀 |
 | 空间|$O(n)$| 存储两个组和前缀和 |

 总复杂度是安全的，因为$n$跨测试的边界是$2 \cdot 10^5$，并且每个操作最多是对数或线性的。
