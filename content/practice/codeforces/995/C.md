 ## 解决方案

 ## 问题理解

 我们得到一系列平面位移向量，每个向量代表从原点或当前位置的移动。 对于每个向量，我们可以独立选择它的方向：我们可以按照给定的方式将其相加或相减。 处理完所有向量后，我们获得平面上的最终点，任务是选择这些符号，使最终点保持在原点周围的固定半径内。 

输入的结构是最多 100,000 个向量的列表，每个向量的坐标大小以 1,000,000 为界。 输出是一系列加号或减号，编码为 1 或 -1，每个向量一个，描述如何确定每次移动的方向。 

该约束立即排除了任何针对符号分配的指数策略。 有 2^n 种可能的选择，对于这种规模的 n 来说，甚至推理所有可能性也是不可能的。 任何有效的解决方案都必须在线性或接近线性时间内构造答案，并且必须在不显式搜索符号配置空间的情况下这样做。 

与可能的累积幅度相比，最终位置的目标界限相对较小。 在最坏的情况下，简单的加法会产生大约 n 乘以 10^6 的坐标，大约是 10^11。 所需的界限 1.5 × 10^6 要小很多数量级，这表明必须在整个过程中仔细执行取消，而不是仅在最后修复。 

一种常见的失败模式是不控制漂移的贪婪积累。 例如，始终选择使 x 坐标保持较小的符号仍然可以允许 y 坐标任意增大。 另一个微妙的失败是试图独立平衡坐标，它忽略了每个决策同时影响两个轴。 

关键的困难在于每个向量同时在两个维度上做出贡献，看起来局部最优的决策可能会造成不可逆转的全局失衡。 

## 方法

 强力解释是尝试每个符号分配并计算结果向量和。 这是正确的，因为它直接评估所有配置的条件，但它需要 2^n 次计算，每次计算都涉及 n 个向量加法，这远远超出了任何可行的限制。 

一种更结构化的强力改进是使用回溯和基于部分向量和的剪枝，但幅度界限太大，剪枝在最坏的情况下无法发挥作用。 状态空间仍然呈指数增长。 

关键的观察结果是，向量的顺序与最终的总和无关，但是可以逐步引导选择符号的_过程_。 我们不是试图直接控制最终向量，而是维护一个运行总和并确保它永远不会偏离受控区域太远。 

核心思想是按大小隐式对向量进行分组，并以分层方式控制它们的贡献。 如果我们按大小对向量进行排序，我们可以首先稳定大向量的贡献，然后使用较小的向量来校正残差。 

这导致了贪婪的平衡策略：在处理新向量时，我们选择它的符号，以便更新的前缀和在欧几里德意义上尽可能接近于零。 这相当于始终选择最小化当前部分和的范数的符号。 

该策略之所以有效，是因为每个步骤都给出了一个二元选择，可以通过将当前位移矢量反射到原点来减少当前位移矢量。 从几何角度来看，我们总是反映下一个向量，以便它将当前的总和拉回到原点，而不是把它推开。

随着时间的推移，这可以确保部分和的行为类似于具有有限漂移的受控随机游走，而不是累积的偏置和。

 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|

 ## 算法演练

 我们将当前位置保持为在原点初始化的向量。 

1. 按给定顺序读取所有向量。 
2. 初始化当前总和`p = (0, 0)`。 
3. 对于每个向量`v_i`，计算两个候选结果：`p + v_i`和`p - v_i`。 
4. 选择产生结果位置的较小平方范数的符号。 

这是使用平方距离而不是欧几里德距离来完成的，以避免浮点运算。 
5. 更新`p`相应地并存储所选的符号。 
6. 处理完所有向量后，输出存储的符号。 

步骤 4 有效的原因是最小化平方距离相当于最小化欧几里德距离，这保证了我们总是选择局部破坏性最小的移动。 

### 为什么它有效

 在每一步中，我们都确保在合并下一个向量后当前位置尽可能接近原点。 关键的特性是，相对于最坏的可能选择，每个决策都会减少或至少阻止规范的增长。 由于每个向量只能翻转方向，因此该算法有效地选择了将运行总和保持在以原点为中心的受控球内的投影。 

这可以防止系统向任何方向漂移。 即使一系列向量倾向于朝一个方向推动，交替的符号选择也可以确保没有一个方向会累积未经检查的幅度。 这个过程的行为就像对原点的重复反射，它限制了整个序列中部分和的增长。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    v = [tuple(map(int, input().split())) for _ in range(n)]
    
    x = 0
    y = 0
    ans = []
    
    for vx, vy in v:
        # try +v
        x1 = x + vx
        y1 = y + vy
        d1 = x1 * x1 + y1 * y1
        
        # try -v
        x2 = x - vx
        y2 = y - vy
        d2 = x2 * x2 + y2 * y2
        
        if d1 <= d2:
            x, y = x1, y1
            ans.append(1)
        else:
            x, y = x2, y2
            ans.append(-1)
    
    print(*ans)

if __name__ == "__main__":
    solve()
```该解决方案维护一个运行的坐标对，并评估每个向量的两个可能的符号结果。 平方距离比较可以避免浮点错误并确保整数运算。 所选符号会立即存储，并且状态会就地更新。 

一个微妙的点是，所有算术都可以安全地适合 64 位整数，因为中间和的最大量值大约为 10^11，并且平方仍然保持在 10^22 之内，这在 Python 的任意精度范围内。

 ## 边缘情况

 经常破坏简单实现的一个特殊情况是所有向量都指向同一方向。 在这种情况下，总是选择 +1 或总是选择 -1 会导致线性增长，而贪婪平衡会翻转足够的向量以保持总和较小。 

例如，使用输入`(1,0)`重复多次，忽略全局平衡的幼稚策略将产生大小为 n 的最终 x 坐标。 贪婪算法在有利时交替符号，使运行总和在零附近振荡而不是漂移。 

另一个微妙的情况是当向量很大并且几乎相互抵消时。 如果两个向量几乎完全相反，则即使存在平衡分配，选择具有相同符号的两个向量也会产生较大的中间和。 该算法通过在每一步评估两个符号选项并立即选择使部分和最接近原点的配置来处理此问题，确保在本地利用取消而不是延迟。
