 ## 解决方案

 ## 问题理解

 我们给出了一个在所有长度的二进制字符串上定义的函数$n$。 将此视为一张桌子$2^n$条目，每个位掩码一个值。 最初，该表中的每个条目都填充了一些数字。 

进行一个游戏来确定该表的哪个条目最终被揭示。 从空分配开始$n$变量中，玩家逐渐分配位，直到形成完整的二进制字符串。 每一步都会随机选择哪个玩家采取行动，该玩家选择一个未分配的位置并为其分配值 0 或 1。分配所有变量后，游戏的值就是与生成的二进制字符串对应的表条目。 

Allen 希望这个最终值较大，Bessie 希望它较小，并且双方都在充分了解牌桌的情况下发挥最佳效果。 

在我们计算出这个游戏的预期结果后，表格略有变化：单个条目被更新，我们必须重新计算预期值。 这种情况会发生多次，每次更新后我们都必须报告新的期望。 

这些限制立即表明我们无法直接模拟游戏。 该表的大小可达$2^{18}$，更新次数也达到$2^{18}$，所以即使$O(n 2^n)$每个查询已经太慢了。 

一种简单的方法是尝试将游戏建模为部分分配的树。 每个状态不仅取决于哪些变量已经固定，还取决于它们的指定值。 这导致了爆炸：跟踪子集和分配的产量$3^n$州，这对于$n = 18$，并且转换涉及极小极大决策，这使得情况变得更糟。 

一个常见的微妙失败案例来自于试图忽略谁先行动的随机性。 例如，如果错误地假设艾伦总是先移动，则该值将成为变量排序上的确定性极小极大，这会产生完全不同的结果。 即使是像这样的小情况$n=2$，当不同的玩家首先行动时，这会导致错误的答案。 

另一个失败来自于假设“分配变量的顺序无关紧要”，这在一般的极小极大游戏中是错误的。 这里的正确性取决于取消，只有在仔细写出最小-最大结构后，取消才变得可见。 

## 方法

 蛮力公式将明确地从空状态模拟游戏。 从每个部分分配中，我们将考虑下一个变量的所有选择，然后在分配 0 或 1 时进行分支，并递归地评估最佳游戏下的结果状态。 这已经形成了一个大致大小的博弈树$n! \cdot 2^n$，因为每个变量排序都可以出现，并且每个赋值都会加倍分支。 即使是激进的记忆也无济于事，因为状态必须对分配的变量及其值进行编码，从而导致$O(3^n)$州。 

关键的简化来自于隔离玩家实际影响的内容。 玩家不直接控制最终的比特串； 他们只选择接下来显示的坐标。 一旦选择了一个坐标，该坐标的最佳响应仅取决于通过将其设置为 0 或 1 获得的两个子树。 

对于固定坐标$i$，假设剩余的游戏值如果我们设置$x_i=0$或者$x_i=1$是$A$和$B$。 如果艾伦移动，他会选择两者中较好的一个，所以结果是$\max(A,B)$。 如果贝西移动，她会选择更糟糕的，给$\min(A,B)$。 由于移动者是按概率选择的$1/2$，选择坐标的期望贡献$i$变成：$$\frac{1}{2}(\max(A,B) + \min(A,B))$$关键的身份是$\max(A,B) + \min(A,B) = A + B$，所以这简化为：$$\frac{A + B}{2}$$对哪个玩家移动的依赖完全消失了。 

这将整个游戏压缩为超立方体上的线性平均过程：选择一个坐标只需通过对其两半进行平均来替换它。 由于平均在坐标之间是可交换的，因此消除变量的顺序并不重要。 

因此，该过程简化为重复应用全维平均，从而得到表中所有值的统一平均值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解游戏树 |$O(3^n)$|$O(3^n)$| 太慢了|
 | 平均观察|$O(2^n + r)$|$O(2^n)$| 已接受 |

 ## 算法演练

 1. 计算所有的初始总和$2^n$表中的值。 这表示任何更新之前分布的总质量。 
2. 将该总和除以$2^n$得到博弈的初始期望值。 游戏的结构将最终结果简化为对所有叶子进行统一平均。 
3. 当更新到达时动态维护总和。 每次更新都会替换一个条目，因此我们减去旧值并添加新值。 
4. 每次更新后，重新计算预期值，即当前总和除以$2^n$。 

### 为什么它有效

 在选择变量的每一步中，两个玩家的最佳响应都会崩溃为取两个子问题的平均值。 这消除了对战略秩序或对抗结构的任何依赖。 由于每个维度都充当线性平均算子，因此组成了所有$n$运算符对所有运算符产生统一的平均值$2^n$树叶。 线性确保局部更新仅影响全局总和，并且有关部分分配的隐藏结构信息不会在该过程中幸存下来。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, r = map(int, input().split())
    size = 1 << n
    arr = list(map(int, input().split()))
    
    total = sum(arr)
    inv = 1.0 / size
    
    print(total * inv)
    
    for _ in range(r):
        z, g = map(int, input().split())
        total -= arr[z]
        arr[z] = g
        total += g
        print(total * inv)

if __name__ == "__main__":
    main()
```该实现仅依赖于维护数组的全局总和。 关键的设计选择是避免任何模拟游戏结构的尝试； 一旦平均属性被认识到，所有博弈论的复杂性都消失了。 仅在打印时进行浮点除法，避免了中间步骤的精度误差累积。 

一个微妙的点是更新必须增量调整总和而不是每次重新计算它，因为重新计算会花费$O(2^n)$每个查询并且在最大输入大小下太慢。

 ## 边缘情况

 当表中的所有值都相同时，就会出现极端情况。 在这种情况下，除了一个条目之外，任何更新仍然保留统一的结构，并且预期值仅通过全局总和调整来改变。 该算法干净地处理了这个问题，因为它从不依赖于方差或结构，只依赖于总和。 

另一个边缘情况是重复更新针对同一索引。 每次从头开始重新计算总和的简单实现仍然是正确的，但速度太慢，而增量更新策略自然会通过在添加新值之前减去前一个值来处理重复覆盖。 

最后，当$r = 0$，解仍然输出正确的初始平均值而不进入更新循环，因为预期值仅取决于初始总和。
