 **标签：** 蛮力，数论
 **求解时间：** 1m 12s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们被要求确定给定的数字是否几乎是幸运的。 如果一个数字能被至少一个幸运数字整除，那么它几乎就是幸运数字。 幸运数字是完全由数字 4 和 7 组成的正整数，如 4、7、44、47、74 等。 输入是单个整数`n`1 到 1000 之间，如果该数字几乎是幸运的，则输出为简单的“YES”，否则输出为“NO”。 

限制非常有限。 自从`n`最多 1000，我们可以检查 1000 以内的每个幸运数字的整除性，而不必担心性能。 这也使我们能够预先计算该范围内的所有幸运数字。 小的上限排除了对高级数论算法或优化筛选技术的需要。 

非明显的边缘情况来自小数字、本身幸运的数字以及是幸运数字的倍数但本身不幸运的数字。 例如，4几乎是幸运的，因为它是幸运的。 数字 16 几乎是幸运的，因为它可以被 4 整除，即使它包含除 4 或 7 之外的数字。粗心的实现可能只会检查是否`n`是幸运的，忽略整除性，这对于 16 或 28 这样的数字来说是失败的。 

## 方法

 一种简单的暴力方法会生成从 1 到`n`并检查每个数字是否是幸运的。 对于找到的每个幸运数字，我们都会检查它是否可以整除`n`。 这种方法是正确的，因为任何几乎幸运的数字都必须能被某个幸运数字整除。 然而，迭代 1000 以内的所有数字并反复检查它们的数字有点多余。 

关键的见解是我们可以使用递归或迭代构造生成 1000 以内的所有幸运数字。 从空数字开始，重复附加 4 或 7，一旦数字超过 1000 就停止。一旦我们有了这个列表，我们只需迭代它并检查整除性。 幸运数字的结构——有限的数字和一个小的上限——使得这变得可行和高效。 我们只检查一小部分有效候选者，而不是检查从 1 到 1000 的每个数字。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n log n) | O(n log n) | O(1) | O(1) | 这里可以接受，但效率低下 |
 | 预先计算幸运数字 | O(L) 其中 L 是幸运数字的数量 ≤1000 | O(L) | 最优，已接受|

 ## 算法演练

 1. 初始化一个列表，保存最多 1000 个幸运数字。我们从 4 和 7 作为基数开始，因为这些是最简单的幸运数字。 
2. 使用队列通过将 4 或 7 附加到队列中的每个数字来迭代生成新的幸运数字。 一旦超过 1000，就停止生成新数字，因为它们无法整除`n`。 
3. 迭代幸运数字列表。 对于每个幸运数字，检查是否`n`使用模运算符可以被它整除。 
4. 如果我们找到任何能整除的幸运数字`n`，打印“YES”并终止。 如果他们都不分开`n`，打印“否”。 

为什么它有效：通过构造，我们枚举了所有可能除以的幸运数字`n`。 由于几乎幸运数字是通过被某个幸运数字整除来定义的，因此根据整个集合检查整除性可以保证正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def generate_lucky_numbers(limit):
    lucky = []
    queue = [4, 7]
    while queue:
        num = queue.pop(0)
        if num > limit:
            continue
        lucky.append(num)
        queue.append(num * 10 + 4)
        queue.append(num * 10 + 7)
    return lucky

n = int(input())
lucky_numbers = generate_lucky_numbers(1000)

for ln in lucky_numbers:
    if n % ln == 0:
        print("YES")
        break
else:
    print("NO")
```我们首先使用简单的类似 BFS 的方法生成 1000 以内的所有幸运数字，附加数字 4 和 7。然后我们迭代生成的数字并检查整除性。 使用`else`于`for`循环确保如果没有幸运数字可以整除，我们只打印“NO”`n`。 

## 工作示例

 ### 示例 1

 输入：`47`| 变量| 价值|
 | ---| ---|
 | n | 47 | 47
 | 幸运数字 | [4, 7, 44, 47, 74, 77, ...] |
 | 迭代期间 ln | 4 → 7 → 44 → 47 |

 在迭代期间，47 可被 47 整除。输出为“YES”。 

### 示例 2

 输入：`16`| 变量| 价值|
 | ---| ---|
 | n | 16 | 16
 | 幸运数字 | [4, 7, 44, 47, 74, 77, ...] |
 | 迭代期间 ln | 4 → 7 → 44 ... |

 16 % 4 == 0。输出为“是”。 这表明该算法可以正确处理几乎幸运的数字，而这些数字本身并不幸运。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(L) | L为≤1000的幸运数字个数； 检查每个的整除性是常数时间。 |
 | 空间| O(L) | 我们存储所有≤1000的幸运数字。 |

 给定 n ≤ 1000，幸运数字的总数很小（低于 20），因此该算法非常高效并且完全在 2s/256MB 限制之内。

 ## 边缘情况

 最小输入`n = 1`产生“NO”，因为 1 不能被任何幸运数字整除。 最大输入`n = 1000`处理正确，因为所有大于 1000 的幸运数字都不会生成，并且我们正确检查所有可能的幸运数字的整除性。 本身是幸运的数字，例如 4、7、47，由于它们是分开的，因此会立即被确认为几乎幸运的数字。 小幸运数字的倍数但本身并不幸运的数字，如 16、28 和 44，也能被我们的整除循环正确检测到。
