 ## 解决方案
 ## 问题理解

 该问题要求我们找到给定数字串中“最幸运”的子串。 最幸运的是，我们指的是仅由数字 4 和 7 组成的子字符串，在字符串中出现尽可能多的次数，并且如果存在平局，则该子字符串按字典顺序最小。 输入字符串可以短至 1 个字符，也可以长达 50 个字符，并且可以包含任何数字，包括零。 输出应该是单个幸运子字符串，如果不存在则为“-1”。 

考虑到最大输入长度为 50 个字符，任何在大约 O(n²) 或 O(n·m) 时间内运行的解决方案都将高效执行。 当字符串根本不包含 4 或 7 时，就会出现一种微妙的边缘情况，在这种情况下，正确答案是“-1”。 另一个边缘情况是当多个幸运子字符串出现相同次数时，但只应返回字典顺序最小的子字符串。 例如，在字符串中`"4747"`, 幸运子串`"4"`和`"7"`每个出现两次，但是`"4"`应该被退回。 

由于输入长度较短，尝试每个子字符串的简单方法是可行的，但我们可以通过注意到只有单个数字“4”和“7”可以最大化子字符串的出现次数来进一步简化，因为任何多位幸运数字的出现频率都严格低于其单个数字。 

## 方法

 暴力方法将生成输入字符串的所有可能的子字符串，过滤那些幸运的子字符串，计算每个子字符串的出现次数，最后选择频率最高的子字符串。 生成长度为 n 的字符串的所有子字符串大约需要 n·(n+1)/2 个子字符串，如果简单地实现的话，计算每个子字符串的出现次数可以使总操作计数为 O(n3)。 当 n ≤ 50 时，这只是可行的，但不必要地复杂。 

关键的观察结果是，任何长度大于 1 的幸运子串单独出现的次数不能多于“4”或“7”。 这是因为较长的子字符串需要连续的数字才能精确匹配。 因此，我们只需要统计‘4’出现了多少次，‘7’出现了多少次。 结果是最常出现的数字，通过选择“4”作为字典顺序较小的选项来打破平局。 这将解决方案从 O(n3) 减少到 O(n)，简单且稳健。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(n²) | 对于 n≤50 可行，但太过分了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化两个计数器，一个用于“4”，一个用于“7”。 这些将跟踪每个字符串在字符串中出现的次数。 这直接针对只有单个数字才能最大化频率的观察。 
2. 迭代字符串中的每个字符。 对于每个字符，如果它是“4”，则递增“4”计数器。 如果是“7”，则增加“7”计数器。 忽略所有其他数字，因为它们不能构成幸运数字。 
3. 数完后，检查哪个数字出现的次数最多。 如果“4”比“7”出现的频率更高，则答案是`"4"`。 如果“7”出现的频率更高，则答案是`"7"`。 如果两者同样出现，则选择`"4"`因为它按字典顺序较小。 
4. 如果字符串中既没有出现“4”也没有出现“7”，则返回“-1”。 

该算法之所以有效，是因为我们保证多位幸运子串的频率不能高于其组成数字。 不变量是，计数后，这两个个位数的幸运数字之一将始终代表任何幸运子串的最大可能频率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()

count4 = 0
count7 = 0

for ch in s:
    if ch == '4':
        count4 += 1
    elif ch == '7':
        count7 += 1

if count4 == 0 and count7 == 0:
    print("-1")
elif count4 >= count7:
    print("4")
else:
    print("7")
```该代码初始化计数器并扫描字符串一次。 只有“4”和“7”影响计数器。 最终的决定是通过简单的比较。 我们首先检查没有幸运数字的特殊情况，返回“-1”。 平局规则自然是通过比较来处理的`count4 >= count7`。

 ## 边缘情况

 当字符串不包含幸运数字时，例如`"1230"`，该算法正确地将两个数字计数为零并输出“-1”。 对于“4”和“7”数量相等的字符串，例如`"4747"`，算法正确地选择“4”。 例如，对于仅一种类型的幸运数字重复多次的字符串，算法会正确返回该数字`"7777"`回报`"7"`。 这些场景中的每一个都由最终比较逻辑显式处理。
