 ## 解决方案
 ## 问题理解

 佩蒂亚走过编号为`1`到`n`。 有些长凳上有饼干小贩。 每当 Petya 到达长凳时，如果满足以下三个条件之一，他就会吃一块饼干：

 1. 长凳上有一个卖家，在这种情况下他会立即购买并吃掉一块饼干。 
2. 他以前从来没有吃过东西。 
3. 至少`d`距离他上次吃饼干已经过去了几分钟。 

第三条规则意味着两个连续的cookie之间最多可以有`d - 1`没有吃饭的长凳。 

在步行开始之前，必须移除一名卖家。 我们需要确定两个值：

 首先，移除一个卖家后，Petya 吃掉的饼干的最小数量。 

其次，有多少不同的卖家在被删除后达到了最低要求。 

关键的观察是`n`可以大到`10^9`，因此模拟每个长凳是不可能的。 幸运的是，卖家的数量要少得多。 在所有测试用例中，卖家总数最多为`10^5`，这强烈表明该解决方案应该大致呈线性`m`。 

一个常见的错误是认为删除卖家只会删除一个 cookie。 有时，删除卖家会产生更大的不间断间隔，从而减少一些自动 cookie。 

例如：```
n = 6
d = 2
s = [2, 5]
```无需移除，Petya 在长凳上吃饭：```
1, 2, 4, 5
```总共 4 块饼干。 

正在删除卖家`2`给出：```
1, 3, 5
```只有 3 块饼干。 

当被移除的卖家坐在替补席上时，会发生另一个微妙的情况`1`。```
n = 10
d = 3
s = [1, 8]
```长椅`1`已经导致第一个cookie。 删除该卖家并不一定会使计数减少 1。 “第一个 cookie”规则仍然在替补席上触发`1`，因此必须仔细计算效果。 

错误的第三个来源是最后一个卖家之后的尾部部分。```
n = 20
d = 5
s = [6, 12]
```从上次吃饼干的位置到上凳的时间间隔`20`也贡献cookie。 忽略最后一段会产生错误的答案。 

## 方法

 蛮力的想法很简单。 对于每个卖家，将其删除，模拟 Petya 的整个行走过程，数饼干，并保留最佳答案。 

模拟本身很容易，因为规则是确定性的。 问题在于规模。 自从`n`或许`10^9`，走过每一个长凳是不可能的。 即使我们以某种方式将模拟压缩为仅依赖于卖家，尝试所有`m`独立清除仍需要大约`O(m²)`工作。 和`m = 10^5`，那将是大约`10^10`运营。 

关键的观察结果是，cookie 总数可以表示为独立区间贡献的总和。 

假设 cookie 被强制放置在以下位置```
1, s1, s2, ..., sm
```哪里的长凳`1`就像一个特殊的强制性起点。 

考虑两个连续的强制 cookie 位置`a < b`。 吃完饭后`a`，自动规则每隔`d`长凳直到到达`b`。 

此间隙贡献的 cookie 数量为```
(b - a - 1) // d
```加上位置上的cookie`b`。 

这意味着每个间隙都独立贡献。 

当卖家被移除时，几乎所有的差距都保持不变。 仅与该卖方相邻的间隙受到影响。 两个相邻的间隙合并为一个更大的间隙。 

这将问题转化为本地更新问题。 我们计算一次原始 cookie 计数，然后为每个卖家计算合并两个相邻间隔时的总变化量。 

这将复杂性从二次降低到线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(m²) 或更差 | O(米) | 太慢了 |
 | 最佳 | 每个测试用例 O(m) | O(米) | 已接受 |

 ## 算法演练

 让```
p = [1] + sellers + [n + 1]
```额外位置`n + 1`是代表走道尽头的哨兵。 

定义```
gap(i) = (p[i] - p[i-1] - 1) // d
```对于每一个相邻的对。 

未删除的 cookie 总数为：```
base = 1 + Σ gap(i)
```领先的`1`代表第一个cookie。 

### 为什么这个公式有效

 在两个强制 cookie 位置之间`a`和`b`, Petya 自动吃掉每一个`d`之后的长凳`a`直到达到`b`。 此类自动 cookie 的数量正好是：```
(b - a - 1) // d
```将所有差距相加并添加初始 cookie 即可得到完整的总数。 

### 步骤

 1. 构建数组```
p = [1] + s + [n + 1]
```2. 计算```
base = 1 + Σ (p[i] - p[i-1] - 1) // d
```这是删除任何卖家之前的 cookie 计数。 
3. 对于每个卖家`s[i]`, 确定其在内部的位置`p`。 
4.让卖家对应`p[k]`。 

在移除之前，受影响的贡献为```
left = (p[k] - p[k-1] - 1) // d
right = (p[k+1] - p[k] - 1) // d
```5. 删除该卖家后，两个区间合并为```
merged = (p[k+1] - p[k-1] - 1) // d
```6. 卖家本身贡献了 1 个强制 cookie，因此删除它就会删除 1 个 cookie。 

新的总数变为```
cur = base - left - right + merged - 1
```7. 跟踪所有值中的最小值`cur`。 
8. 计算有多少卖家达到了最低要求。 

### 为什么它有效

 每个 cookie 计数都可以分解为相邻强制 cookie 位置的贡献。 删除卖家仅影响接触该卖家的两个时间间隔。 其他间隔保持不变。 

该公式减去两个旧的区间贡献，插入合并的区间贡献，并删除卖家自己的强制 cookie。 由于步行的所有未更改部分都保留完全相同的行为，因此结果值等于删除后的真实 cookie 计数。 

由于每个卖家都经过独立且准确的评估，因此最小值及其频率可以正确计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m, d = map(int, input().split())
        s = list(map(int, input().split()))

        p = [1] + s + [n + 1]

        base = 1
        for i in range(1, len(p)):
            base += (p[i] - p[i - 1] - 1) // d

        best = 10**18
        cnt = 0

        for k in range(1, m + 1):
            left = (p[k] - p[k - 1] - 1) // d
            right = (p[k + 1] - p[k] - 1) // d
            merged = (p[k + 1] - p[k - 1] - 1) // d

            cur = base - left - right + merged - 1

            if cur < best:
                best = cur
                cnt = 1
            elif cur == best:
                cnt += 1

        print(best, cnt)

solve()
```数组`p`包含强制 cookie 事件的所有位置。 长椅`1`被插入是因为 Petya 最初总是在那里吃饭。 哨兵`n + 1`使最终片段使用与其他片段相同的公式。 

变量`base`在删除任何卖家之前存储 cookie 计数。 每个差距都有贡献`(length // d)`自动cookies。 

对于指数卖家`k`，只有两个相邻的间隙可以改变。 计算：```
base - left - right + merged
```用合并版本替换这两个间隙。 

然后我们再减去一个，因为卖家自己的强制cookie消失了。 

最常见的实施错误是忘记哨兵`n + 1`。 如果没有它，最后一个卖家之后生成的cookie将不被计算在内。 

另一个常见的错误是在替补席上对卖家处理不当`1`。 治疗台`1`作为普通卖家会导致重复计算。 插入的起始位置自然可以处理这种情况。

 输入：```

p = [1, 2, 5, 7]

 | 间隔| 贡献 |
 | --- | --- |
 | 1 → 2 | 0 |

 | 5 → 7 | 0 |```

```等等，卖家本身是通过区间结构进行编码的，因此评估移除量才是重要的：

 | 已删除卖家 | 左| 对| 合并| 结果 |
 | --- | --- | --- | --- | --- |
 | 2 | 0 | 1 | 2 | 3 |
 | 5 | 1 | 0 | 2 | 4 |

输出：```
3 1
```此示例展示了合并两个间隔如何减少的不仅仅是卖家自己的 cookie。 

### 示例 2

 输入：```
n = 8
m = 3
d = 2
s = [3, 5, 8]
```建造：```
p = [1, 3, 5, 8, 9]
```计算：

 | 差距| 贡献 |
 | --- | --- |
 | 1 → 3 | 0 |
 | 3 → 5 | 0 |
 | 5 → 8 | 1 |
 | 8 → 9 | 0 |

 根据：```
1 + 0 + 0 + 1 + 0 = 2
```去除分析：

 | 卖家 | 左| 对| 合并| 饼干 |

这表明只有相邻的间隔才重要。

 ## 边缘情况

 考虑：```
n = 2
m = 2
d = 2
s = [1, 2]
```长椅`1`里面有一个卖家，但 Petya 无论如何都会在那里吃，因为这是第一块饼干。 正在删除卖家`1`不会删除第一个 cookie。 间隔公式可以自然地处理这个问题，因为长凳`1`总是包含在`p`。 

考虑：```
n = 20
m = 2
d = 5
s = [6, 12]
```最后一段来自`12`到`20`生成自动cookie。 哨兵`n + 1 = 21`将此尾部转换为普通区间。 不需要特殊情况逻辑。 

考虑：```
n = 10
m = 4
d = 9
s = [2, 8, 9, 10]
```每个删除的卖家都会给出相同的答案。 该算法独立检查每个卖家，并计算所有达到最小值的移除量，产生`4 4`。 

这些情况正是临时模拟往往会失败的地方，而基于区间的公式则保持统一和正确。
