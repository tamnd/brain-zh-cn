 ## 解决方案
 ## 问题理解

 我们有一个大小为的方形盒子`2^n × 2^n`。 在这个盒子里，我们反复放置特殊的三角形饼干。 

一块大小的饼干`k`占据a的上三角部分`k × k`正方形，包括主对角线。 其面积为：$$1 + 2 + 3 + \dots + k = \frac{k(k+1)}{2}$$饼干不能旋转，因此每个饼干始终指向同一方向。 

打包过程是贪心的。 在每一步中，我们都会选择仍然可以容纳在剩余空白空间中的某个位置的最大的cookie，将其放置，并继续，直到至少没有大小相同的cookie`2`可以再放置。 饼干大小`1`不存在。 

任务是计算此过程完成后有多少晶胞保持为空。 由于数字增长很快，因此必须以模数形式打印答案`10^6 + 3`。 

约束较小，`n ≤ 1000`，但实际电路板尺寸是`2^n × 2^n`，变得天文数字般大。 例如，当`n = 1000`，边长本身有300多位小数。 任何试图明确构建董事会的方法都是不可能的。 即使存储一行也已经是不可行的。 

这立即告诉我们解决方案必须来自于识别数学模式。 

一个微妙的边缘情况出现在`n = 0`。 电路板尺寸变为`1 × 1`，但是饼干的大小`1`不存在。 盒子仍然是空的。 

输入：```
0
```正确输出：```
1
```假设每块板都可以容纳至少一个 cookie 的粗心实现会错误地打印`0`。 

另一个容易犯的错误是误解了贪婪过程。 包装不是随意的。 总是首先选择尽可能大的 cookie。 例如，对于`n = 1`，董事会是`2 × 2`。 2 号饼干正好适合一次并覆盖 3 个单元格，留下 1 个空单元格。 

输入：```
1
```正确输出：```
1
```如果有人错误地认为之后也可以使用较小的 cookie，他们可能会尝试用不存在的 size-1 cookie 填充剩余的单元格。 

最后一个陷阱是具有固定宽度整数的语言中的整数溢出。 板面积为：$$(2^n)^2 = 4^n$$为了`n = 1000`，这个数字是巨大的。 必须在求幂期间应用模数，而不是在构建完整值之后应用模数。 

## 方法

 最直接的方法是在网格本身上模拟打包过程。 我们可以代表`2^n × 2^n`板，反复搜索适合的最大饼干，放置它，然后继续，直到没有剩余位置为止。 

这适用于较小的值`n`。 例如，当`n = 3`，董事会仅`8 × 8`，所以暴力是可以控制的。 问题是边长每增加一倍`n`。 在`n = 20`，电路板已经包含超过一万亿个单元。 即使对网格进行一次迭代也变得不可能。 

暴力破解的想法失败了，因为它将棋盘视为任意几何形状，而实际过程具有非常严格的递归结构。 

关键的观察结果是贪婪打包创建了完美的递归分解。 

从一个开始`2^n × 2^n`木板。 最大的饼干大小正好合适`2^n`。 该饼干占据了棋盘的整个上三角部分。 

尚未发现的是右下半部分的另一个三角形区域。 移动坐标后，剩余区域的形状与原始尺寸问题完全相同`2^{n-1}`。 

这意味着重复出现的空单元格数量。 

让`f(n)`是一块尺寸的板中未覆盖的单元格的数量`2^n × 2^n`。 

最大的 cookie 涵盖：$$\frac{2^n(2^n+1)}{2}$$电路板总面积为：$$4^n$$放置最大 cookie 后未覆盖的区域成为参数相同问题的另一个实例`n-1`。 

用小值进行实验表明：$$f(0)=1$$

$$f(1)=1$$

$$f(2)=3$$

$$f(3)=9$$这是一个几何级数：$$f(n)=3^{n-1} \quad \text{for } n \ge 1$$递归式也可以正式推导：$$f(n)=3f(n-1)$$每个递归细分都会创建先前未覆盖模式的三个副本。 

一旦确定了模式，问题就简化为模幂运算。

 | 最佳| O(log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取整数`n`。 
2.特殊情况处理`n = 0`。 

董事会是`1 × 1`，并且不能放置 cookie，因为最小 cookie 大小为`2`。 单个单元格仍然是空的，所以答案是`1`。 
3.为了`n ≥ 1`，使用导出公式：$$f(n)=3^{n-1}$$这是根据每个最大 cookie 放置后未覆盖区域的递归结构得出的。 

1. 计算幂模`10^6 + 3`。 

Python 的内置`pow(base, exp, mod)`在对数时间内执行快速二进制求幂。 
2. 打印结果。 

### 为什么它有效

 贪心进程总是先放置尽可能大的 cookie，即大小为 的 cookie`2^n`。 放置后，剩余的未覆盖区域会分成更小的区域，重现与原始问题相同的几何结构。 

每个递归级别恰好生成先前未覆盖配置的三个独立副本。 由于基本情况包含一个未覆盖的单元格，因此未覆盖的单元格数量在每一级都会增加三倍：$$f(n)=3f(n-1)$$解决这个递归问题可以得到：$$f(n)=3^{n-1}$$为所有人`n ≥ 1`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**6 + 3

n = int(input())

if n == 0:
    print(1)
else:
    print(pow(3, n - 1, MOD))
```实现故意很短，因为问题的困难部分是发现重现，而不是对其进行编码。 

第一个分支处理唯一的例外情况。 什么时候`n = 0`，棋盘太小，无法放置任何 cookie，因此答案恰好是一个空单元格。 

对于所有较大的值，该解决方案使用封闭式递归：$$f(n)=3^{n-1}$$内置的`pow`具有三个参数的函数使用重复平方有效地计算模幂。 这避免了构造巨大的中间数，例如`3^999`。 

一个容易出现的差一错误是使用`3^n`而不是`3^{n-1}`。 检查小值会立即暴露问题：

 对于`n = 1`，答案一定是`1`， 不是`3`。

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

MOD = 10**6 + 3

def solve():
    input = sys.stdin.readline

    n = int(input())

    if n == 0:
        print(1)
    else:
        print(pow(3, n - 1, MOD))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("3\n") == "9\n", "sample 1"

# minimum size
assert run("0\n") == "1\n", "n = 0"

# smallest non-trivial board
assert run("1\n") == "1\n", "single size-2 cookie"

# small recursive case
assert run("2\n") == "3\n", "tripling starts"

# larger value
assert run("5\n") == "81\n", "3^(5-1)"

# maximum boundary style test
expected = str(pow(3, 999, MOD)) + "\n"
assert run("1000\n") == expected, "large exponent modulo"

 ## 边缘情况

 第一个重要的边缘情况是尽可能小的电路板。 

输入：```
0
```电路板尺寸为：$$2^0 = 1$$因此，该板仅包含一个单元格。 由于饼干的大小`1`不存在，不能放置任何东西。 

该算法立即触发特殊情况分支并打印：```
1
```如果没有这个分支，公式`3^{n-1}`会错误地需要计算`3^{-1}`。 

第二个边缘情况是第一个可以放置的板。 

输入：```
1
```电路板尺寸为`2 × 2`。 贪婪进程放置了一个 size-2 cookie：$$\frac{2(2+1)}{2}=3$$三个单元被覆盖，一个仍然空着。 

该算法计算：$$3^{1-1}=3^0=1$$与实际配置相符。 

最后一个重要的边缘情况非常大`n`。 

输入：```
1000
```板边长变为`2^{1000}`，这远远超出了显式计算的范围。 该算法从不构造棋盘或任何巨大的数组。 它仅评估：$$3^{999} \bmod (10^6+3)$$使用对数时间求幂，因此它保持快速且内存高效。
