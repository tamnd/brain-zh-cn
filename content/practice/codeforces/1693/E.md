 ## 解决方案
 ## 问题理解

 我们得到一个长度的数组$n+2$，其中第一个和最后一个元素固定为零，中间$n$元素是任意非负整数。 任务是使用一组特定的操作将所有元素减少到零：在每一步中，我们可以选择最左边或最右边的最大元素，并将其替换为所选方向上相邻元素的最大值。 目标是通过最少的操作次数来实现这一目标。 

约束条件告诉我们$n$最多可达 200,000。 一个简单的模拟，重复搜索最左边或最右边的最大值$O(n)$每个操作将不起作用，因为每个元素可能会被减少多次，可能导致$O(n^2)$步骤，对于$n$数十万。 因此，我们需要一种大致在线性时间内工作的方法。 

非明显边缘情况包括所有元素都等于 0 的数组、存在多个最大值的平台以及最大元素位于边界处的数组。 例如，像这样的数组`[0, 0, 0, 0, 0, 0]`应立即产生零操作。 另一种情况如`[0, 3, 3, 3, 0]`测试算法是否正确识别高原中最左边或最右边的最大值，并有效地减少它们。 

## 方法

 暴力解决方案将重复找到最左边和最右边的最大值，根据规则更新它们，并计算操作。 虽然正确，但它会扫描数组$O(n)$每次操作的次数。 在最坏的情况下，每个元素可能需要最多其值的操作次数，大致给出$O(n^2)$，这对于给定的约束来说太慢了。 

关键的见解来自于观察，这些操作本质上允许我们通过数组将值“传播”到零。 每个元素仅通过最大值与其邻居进行交互。 我们可以通过考虑严格大于其左侧或右侧的元素来计算每个元素需要多少次操作，而不是模拟每个操作。 具体来说，减少一个值所需的操作数是其主导的任何元素所需的最大操作数加一。 这在某种意义上将问题转化为计算最长的“递减路径”：从边界（零）开始，向内传播以计算所需的最小步数。 

通过使用堆栈或单调结构处理数组，我们可以计算每个段在线性时间内贡献的步数。 这避免了重复扫描最大值并将时间复杂度从二次降低到线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 在数组前面和后面添加一个零以统一处理边界。 设新数组为$a$长度$n+2$。 这确保了所有最大减少量最终都达到零。 
2. 初始化一个堆栈，该堆栈将有助于按降序跟踪元素的位置。 该堆栈使我们能够有效地确定每个最大值左侧或右侧的下一个较小元素。 
3. 从左到右遍历数组。 对于每个元素，从堆栈中弹出元素，直到顶部大于或等于当前元素。 位置的差异给出了从左侧减少当前元素所需的操作数。 将此值存储在左操作数组中。 
4. 如果我们从右侧传播值，则从右到左重复相同的过程来计算所需的操作。 将其存储在右操作数组中。 
5. 对于每个元素，将其减为零所需的操作总数是其左操作和右操作的总和。 答案是所有元素的总和，不包括边界处的人为零。 
6. 输出最终的和。 

工作原理：堆栈确保我们能够有效地为每个元素找到最近的严格较小的元素，这决定了值在任一方向上减少需要多少步。 因为每个元素都被处理两次（一次从左开始，一次从右开始），所以我们永远不会过度计数。 这保证了我们计算最少的操作数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    a = [0] + arr + [0]
    n += 2  # include boundaries

    left_ops = [0]*n
    stack = []
    for i in range(n):
        while stack and a[stack[-1]] < a[i]:
            stack.pop()
        if stack:
            left_ops[i] = left_ops[stack[-1]] + 1
        stack.append(i)

    right_ops = [0]*n
    stack = []
    for i in range(n-1, -1, -1):
        while stack and a[stack[-1]] < a[i]:
            stack.pop()
        if stack:
            right_ops[i] = right_ops[stack[-1]] + 1
        stack.append(i)

    total_ops = 0
    for i in range(1, n-1):
        total_ops += left_ops[i] + right_ops[i]
    print(total_ops)

if __name__ == "__main__":
    solve()
```该解决方案首先用零填充数组以避免边界检查。 然后，它通过考虑左侧和右侧最近的较大元素，使用单调堆栈来计算减少每个元素所需的最小操作数。 这保证了我们永远不会不必要地处理一个元素两次以上。

 ## 边缘情况

 对于数组`[0, 0, 0]`，该算法将每个元素的 left_ops 和 right_ops 计算为零。 总和为零，符合预期。 对于高原`[0, 3, 3, 3, 0]`，堆栈正确地找到最近的较大元素来传播减少，避免计数过多。 由于填充了零，该算法自然地处理边界，因此我们不需要第一个或最后一个元素的特殊情况。
