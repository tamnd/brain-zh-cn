 ## 解决方案
 ## 问题理解

 我们得到了一个有向图，代表意大利由道路连接的城市。 Keshi 从城市 1 出发，想要到达城市 n，AmShZ 正在那里等待。 每天，AmShZ 都可以将一条道路标记为封锁或指示 Keshi 移动。 如果克什移动，他会从他所在位置的当前可到达的所有城市中随机选择。 任务是确定 AmShZ 可以保证 Keshi 联系到他的最短天数，无论 Keshi 选择的随机性如何。 

输入提供城市数量`n`和道路`m`， 其次是`m`有向边。 输出是一个整数`d`，保证克什到达n城市所需的最小天数。 

限制条件很高：`n`和`m`可以达到`2 * 10^5`。 这意味着任何算法都比`O(n + m)`或者`O((n + m) log n)`不太可能在 2 秒内运行。 像模拟所有堵塞道路序列或随机移动这样的二次方法是完全不可行的。 同一对城市之间允许有多个边，因此我们不能假设一个简单的邻接矩阵或每个城市对最多由一条道路连接。 

当某个城市有多条通往目的地的距离差异很大的外出道路时，就会出现不明显的边缘情况。 例如，如果城市 1 有通往城市 2 和 3 的道路，其中城市 2 以 1 步通向城市 n，而城市 3 以 100 步通向城市 n，则不阻塞道路的幼稚策略可能会导致最坏的情况为 100 天。 正确的解决方案需要确定最优阻塞后的最长保证路径，而不是最短随机路径。 

## 方法

 暴力破解的想法是模拟所有阻塞决策序列。 对于每个城市，如果克什随机移动，我们可以计算到达城市 n 的预期天数。 然后，我们将模拟每种阻塞道路的选择，以尽量减少最长可能的天数。 这适用于微小的图，但序列的数量随着每个城市的传出边的数量呈指数增长。 和`m`最多`2 * 10^5`，这是完全不可行的。 

关键的观察结果是，问题简化为计算**最坏情况下所需的最小天数**，这相当于找到类似于“最佳阻塞下到 n 的距离”的度量。 不要考虑随机向前移动，而是考虑从城市 n** 向后的问题。 每个城市都可以分配一个数字，表示在最坏的情况下到达城市 n 需要多少天。 对于具有传出边缘的城市，最佳策略是首先阻塞通向此类数字最多的城市的边缘。 最终，一个城市的天数是**其子级中的最大天数**加上一，以考虑阻塞。 

这给出了使用**反向图上的拓扑排序**的线性时间解决方案。 每个城市的“距离”是根据其可以到达的城市的距离计算的，并考虑了传出边缘的数量。 这完全避免了模拟随机性，因为最佳拦截器确保 Keshi 每天遵循最大化向城市 n 前进的路径。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^m) | O(2^m) | O(n + m) | 太慢了|
 | 最佳 | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 构造**反转图**，其中边指向`u`到`v`如果原始边是`v`到`u`。 这使我们能够向后推断距城市 n 的距离。 
2.初始化一个数组`days_to_n`长度`n + 1`和`0`对于n城市，因为Keshi已经在那里了。 
3. 计算反转图的**拓扑顺序**。 这确保了在处理城市时，从该城市可到达的所有城市都已分配了它们的日期。 
4. 对于拓扑顺序中的每个城市，确定达到 n 的天数。 对于一个城市来说`v`与传出边缘`u1, u2, ..., uk`，按**降序对这些目的地进行排序`days_to_n`**。 然后分配`days_to_n[v]`作为`1 + max(days_to_n[ui] + i)`， 在哪里`i`是排序列表中的索引。 这`+i`考虑首先阻塞较难的路径。 
5.所有城市处理完毕后，答案为`days_to_n[1]`。 这代表 AmShZ 需要保证 Keshi 从 1 号城市到达他身边所需的最短天数。 

为什么有效：反转图和拓扑排序确保每个城市最坏情况的天数仅取决于其子级的值，这些值已经计算出来。 对传出边进行排序可确保阻塞策略最大化效率：较长的路径首先被阻塞，因此 Keshi 被迫采取通向最小保证天数的路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import defaultdict, deque

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    outdeg = [0] * (n + 1)
    
    for _ in range(m):
        v, u = map(int, input().split())
        g[u].append(v)  # reverse graph
        outdeg[v] += 1

    days = [0] * (n + 1)
    q = deque([n])
    
    while q:
        node = q.popleft()
        for prev in g[node]:
            outdeg[prev] -= 1
            days[prev] = max(days[prev], days[node] + 1)
            if outdeg[prev] == 0:
                q.append(prev)
    
    print(days[1])

solve()
```在此实现中，我们反转边以从城市 n 向后进行推理。 这`outdeg`数组跟踪每个城市有多少个未处理的传出边缘。 通过反复处理城市`outdeg`达到零时，我们可以有效地计算最坏情况的天数。 使用`max(days[prev], days[node] + 1)`确保我们考虑到 Keshi 可能被迫沿着的最长路线，反映最佳阻塞。
