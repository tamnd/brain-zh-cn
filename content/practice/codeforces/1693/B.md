 ## 解决方案
 ## 问题理解

 我们得到了一棵有根的树。 每个顶点都以值开始`0`，以及每个顶点`v`有规定的间隔`[l_v, r_v]`。 

操作选择一些根到顶点的路径并沿着该路径添加值。 当我们从根向所选顶点移动时，添加的值必须形成一个非递减序列。 

执行一定数量的操作后，每个顶点值必须位于其允许的区间内。 任务是找到最少的操作次数。 

乍一看，该操作看起来很复杂，因为它修改了整个路径，并且添加的序列受到限制。 关键的挑战是了解每个顶点实际上可以生成哪些值以及操作如何在树上交互。 

该树最多包含`2 · 10^5`所有测试用例的顶点。 任何重复遍历路径或显式模拟操作的解决方案都会太慢。 由于总大小仅为`2 · 10^5`， 一个`O(n)`或者`O(n log n)`预计每个测试文件的解决方案。 

一个微妙的点是操作可以同时影响祖先和后代。 试图独立满足顶点的贪婪策略很容易会过度计算。 

考虑：```
1
|
2
```和```
[1,5]
[2,9]
```一次操作已经可以满足两个顶点。 单独处理每个顶点会错误地回答`2`。 

另一个容易犯的错误是假设每个顶点最终都必须准确接收`l_v`。 

例子：```
1
|
2
```和```
[1,100]
[50,100]
```如果顶点`2`接收价值`50`，然后顶点`1`自动接收至少`50`以及。 这是完全有效的，因为`50`仍然躺在里面`[1,100]`。 

当子树无法提供足够的贡献来满足其父树时，就会出现第三个陷阱。 

例子：```
    1
   / \
  2   3

[10,10]
[1,1]
[1,1]
```孩子们共同贡献的只是`2`。 顶点`1`至少还需要价值`10`，强制在其子树中进行额外的操作。 任何只聚合子贡献而不检查下限的方法在这里都会失败。 

## 方法

 蛮力观点是直接从运营角度思考。 我们可以尝试构建满足所有间隔的操作，同时最小化它们的计数。 不幸的是，可能的操作空间是巨大的。 每个操作选择一条路径、长度和任意非递减整数序列。 即使对于小树来说，可能性也呈指数级增长，使得显式搜索变得毫无希望。 

关键的观察是我们实际上不需要了解操作本身。 

假设我们处理一个以`v`。 想象一下，在该子树内创建的所有操作都贡献了一定的总量`s`到顶点`v`。 

对祖先来说重要的只是这个总量。 具体的操作分布如下`v`变得无关紧要。 

现在考虑顶点处发生的情况`v`。 

如果其孩子的累计贡献已经至少`l_v`，那么我们可以将向上传递的值限制在`min(s, r_v)`。 发送超过`r_v`向上是没有用的，因为最终值`v`不能超过`r_v`。 

如果累计贡献小于`l_v`，那么现有子树操作的组合都不能满足`v`。 我们被迫创建一个新操作，其最高有用点位于该子树内。 为了最大化未来利益，我们设定`v`直接到`r_v`。 这有助于`r_v`向上并且只花费一次操作。 

这自然会导致后序 DFS。 

对于每个顶点，我们计算在优化处理其整个子树后它可以向上贡献的量。 

叶子尤其显眼。 一片叶子最初贡献`0`。 如果`0 < l_v`，我们必须在那里开始一项操作并返回`r_v`。 这符合直觉，即具有积极需求的叶子需要自己的操作。 

整个解决方案成为一棵贪婪树 DP，其中每个顶点要么接受来自其子节点的总和，要么开始一个新操作。

 ## 算法演练

 1. 以顶点为树根`1`。 
2. 按后序处理顶点，这意味着每个子节点都在其父节点之前处理。 
3. 对于一个顶点`v`，计算：```
sum_children = Σ contribution(child)
```这是已经可用的总价值`v`来自其后代内部创建的操作。 
4.如果`sum_children < l_v`，则子树不能满足`v`。 

创建一项新操作。 

将答案增加`1`。 

返回`r_v`作为该子树对父树的贡献。 

新的运营有效提高了`v`发挥最大的利用价值，给祖先最大的帮助。 
5. 否则，`v`无需创建新操作即可满足。 

返回：```
min(sum_children, r_v)
```以上任意金额`r_v`无法使用，因为`v`必须保持在其间隔内。 
6. 处理完根后，累加的答案就是最少的运算次数。 

### 为什么它有效

 对于每个顶点，与其父顶点相关的唯一信息是可以向上传播同时保持整个子树有效的最大可行值。 

如果后代操作提供小于`l_v`，没有办法满足`v`无需在其子树中的某处引入新操作。 创建一个操作就足够了，并将结果贡献设置为`r_v`总是最优的，因为更大的贡献可以帮助祖先，而不会造成伤害。 

如果后代操作已经提供至少`l_v`，则无需创建另一个操作。 向上传递的最佳贡献是允许的最大值`v`，即`min(sum_children, r_v)`。 

通过在每个顶点做出这种局部最优选择，我们可以最大限度地提高对祖先的帮助，同时不会使用不必要的操作。 任何解决方案都必须在任何时候创建一个操作`sum_children < l_v`，所以贪婪的决定是被迫的。 这证明了最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans_list = []

    for _ in range(t):
        n = int(input())

        parent = [0] * (n + 1)
        children = [[] for _ in range(n + 1)

]
        p = list(map(int, input().split()))

        for i in range(2, n + 1):
            parent[i] = p[i - 2]
            children[parent[i]].append(i)

        l = [0] * (n + 1)
        r = [0] * (n + 1)

        for i in range(1, n + 1):
            l[i], r[i] = map(int, input().split())

        order = []
        stack = [1]

        while stack:
            v = stack.pop()
            order.append(v)
            for u in children[v]:
                stack.append(u)

        value = [0] * (n + 1)
        answer = 0

        for v in reversed(order):
            s = 0
            for u in children[v]:
                s += value[u]

            if s < l[v]:
                answer += 1
                value[v] = r[v]
            else:
                value[v] = min(s, r[v])

        ans_list.append(str(answer))

    sys.stdout.write("\n".join(ans_list))

if __name__ == "__main__":
    solve()
```第一部分从父数组构建有根树。 

DFS 是迭代实现的，以避免 Python 递归深度问题。 我们首先生成一个遍历顺序，然后对其进行反向处理，产生后序遍历。`value[v]`存储子树的数量`v`优化处理后可以向上贡献。 

当累计子女缴款额低于`l[v]`，新的操作是不可避免的。 我们计算它并将贡献设置为`r[v]`。 

否则子树已经有效。 贡献金额不能超过`r[v]`，所以我们用`min(s, r[v])`。 

该值可以达到`2 · 10^5 × 10^9`，所以Python的任意精度整数很方便。 在具有固定宽度整数的语言中，需要 64 位类型。

 ## 边缘情况

 ### 父级必须创建一个新操作

 输入：```
1
3
1 1
10 10
1 1
1 1
```加工：```
vertex 2 -> contribution 1
vertex 3 -> contribution 1
root sum = 2
```自从`2 < 10`，子孙不能满足根源。 该算法添加一个操作并将根贡献设置为`10`。 答案就变成了`1`，这是最优的。 

### 大子捐款超过 r

 输入：```
1
3
1 1
1 3
5 5
5 5
```加工：```
vertex 2 -> 5
vertex 3 -> 5
root sum = 10
```根只允许值达到`3`，因此向上返回的贡献变为`3`。 

如果没有`min(sum, r[v])`钳制，祖先会错误地认为存在比实际允许的更多的可用价值。 

### 具有正下界的叶子

 输入：```
1
2
1
1 100
50 100
```叶子以子和开始`0`，即下面的`50`。 一项操作是强制性的。 

该算法创建该操作并返回`100`。 根自动获得足够的价值，不需要其他任何东西。 

回答：```
1
```这说明了为什么叶子经常发起操作以及为什么选择`r_v`使未来利益最大化。
