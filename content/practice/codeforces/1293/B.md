 ## 解决方案
 ## 问题理解

 游戏可以看作是一个过程，我们从`n`对手并反复触发回合，消除其中一些。 在每一轮中，如果有`s`对手仍在比赛中并且完全`t`他们中的一些人没有通过当前的问题，JOE 获得`t/s`美元和那些`t`被淘汰的球员将被永久移除。 其余`s - t`继续下一轮。 

关键的自由在于我们可以决定每轮有多少对手失败，只要介于`0`以及目前的幸存者人数。 当没有对手剩余时，该过程结束。 

目标是选择一系列消除顺序，使 JOE 赚取的总金额最大化。 

约束条件`n ≤ 100000`意味着任何试图模拟所有可能的轮次分配淘汰方式的解决方案都是不可行的。 对选择的天真搜索`t`每个状态都有大量分支，并且很快呈指数级增长。 即使对所有可能的剩余状态进行二次动态规划也会太慢。 

输出是一个实数，因此我们还需要一种稳定的方法来计算可能涉及最多的总和`n`分数项。 

一些边缘情况对于正确性很重要。 什么时候`n = 1`，只有一个对手，唯一有意义的行动就是在一轮中消灭他们，给予奖励`1/1 = 1`。 任何错误地假设多轮或分裂的推理都会在这里破裂。 当人们认为一次消除许多对手是有益的时，就会出现另一种微妙的失败情况。 例如，取所有`n`立即产生回报`n/n = 1`，在本地看起来不错，但完全忽略了未来的回合。 

## 方法

 暴力视图对待每个状态`s`作为选择：选择任何`t`从`1`到`s`， 获得`t/s`，并移至`s - t`。 这形成了决策树。 虽然原则上是正确的，但它会爆炸，因为每个状态分支最多`s`的可能性，导致大量的序列，即使是中等程度的`n`。 

关键的简化来自于比较当我们将淘汰分为多轮和将它们分组为一轮时奖励的累积方式。 假设在某个状态`s`我们消除`k`对手。 在一轮中完成它给出`k/s`。 相反，如果我们在不同的回合中将它们一一淘汰，那么贡献就变成了`1/s + 1/(s-1) + ... + 1/(s-k+1)`，它严格更大，因为每个分母都减少，而分子保持不变`1`。 

这意味着将消除集中到大批量中总是比将它们分散到单个消除中更糟糕。 因此，最优策略是强制的：在每一轮中我们恰好消灭一个对手。 

一旦这个问题得到解决，这个过程就变得确定了。 开始于`n`，我们去`n-1`， 然后`n-2`，依此类推，直到`1`，累积倒数的简单和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力淘汰选择 | 指数| O(n) 递归 | 太慢了|
 | 最优谐波策略 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 ### 最优策略

 1. 开始于`s = n`和总奖励`ans = 0`。 这代表仍在游戏中的对手数量和累积的金钱。 
2. 在每一步中，决定只消除一个对手，这意味着`t = 1`。 这是最小可能的非零消除，任何更大的批次都不是最佳的，因为它会更早地使用更大的分母。 
3.添加奖励`1/s`到答案。 这反映了恰好有一个对手被排除在外`s`其余的。 
4. 减少`s`减少一分，因为恰好有一名对手被淘汰。 
5. 重复直到`s`变为零。 到那时，所有对手都已被淘汰，过程停止。 

### 为什么它有效

 核心属性是分裂任何消除尺寸`k`进入`k`单独的单次消除总是会增加总奖励，因为每个后续分数都使用较小的分母。 这创建了一种强制结构：任何最佳解决方案都可以转化为每一轮仅删除一个对手而不减少答案的解决方案。 在这种结构下，状态序列是唯一的`n, n-1, ..., 1`，因此总奖励是固定且最大的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())

ans = 0.0
for i in range(1, n + 1):
    ans += 1.0 / i

print(ans)
```该实现直接计算谐波和`1`到`n`。 向上或向下迭代是等价的； 在这里我们总结`1/i`为了清楚起见。 

关键的微妙之处在于使用浮点除法。 由于所需的精度为`1e-4`，标准双精度累加足以满足`n`最多`10^5`。

 最终的答案是`1 + 1/2 + 1/3 = 1.8333...`。 这显示了每一步如何对应于消除一个对手。

## 测试用例```python
import sys, io

def solve():
    n = int(sys.stdin.readline())
    ans = 0.0
    for i in range(1, n + 1):
        ans += 1.0 / i
    print(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as sio
    out = sio.StringIO()
    with redirect_stdout(out):
        solve()
    sys.stdin = old_stdin
    return out.getvalue().strip()

# provided samples
assert abs(float(run("1")) - 1.0) < 1e-9

# custom cases
assert abs(float(run("2")) - (1 + 1/2)) < 1e-9
assert abs(float(run("3")) - (1 + 1/2 + 1/3)) < 1e-9
assert abs(float(run("10")) - sum(1/i for i in range(1, 11))) < 1e-9
assert abs(float(run("100000")) > 0)  # sanity check
```| 测试输入| 预期产出 | 它验证了什么 |

 ## 边缘情况

 当`n = 1`，该算法恰好执行一次加法`1/1`。 任何假设不同消除大小之间至少有一种“选择”的方法在这里都会失败，因为根本没有分支。 

什么时候`n`很大，比如`100000`，总和增长缓慢并且取决于许多小的分数贡献。 尝试显式模拟消除序列的方法将超出时间限制，而谐波求和仍保持线性且稳定。 

当考虑浮点精度时，累加顺序不会显着影响所需容差的正确性，但混合整数除法或不正确的转换会立即破坏结果。
