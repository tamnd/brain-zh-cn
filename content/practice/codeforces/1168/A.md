 ## 解决方案
 ## 问题理解

 我们得到一个循环值数组，其中每个元素都位于从零到某个固定模减一的范围内。 一种操作包括选择位置的任意子集，并将所有选定的值加一，并在模数边界处进行环绕。 

目标是使用尽可能少的此类全局增量操作将数组转换为非递减序列。 每个操作在时间上都很“昂贵”，但范围很灵活，因为它可以影响索引的任何子集。 

主要困难在于成本模型中每个索引的增量并不是独立的。 我们不是在计算每个位置接收到多少增量，而是计算需要多少同步轮次，其中每一轮可以将位置的任何子集前进一步。 

约束足够大，任何显式模拟操作或探索子集的解决方案都是不可能的。 对于多达 300,000 个元素，即使是线性通道也可以，但任何二次或涉及每个值重复扫描的操作都太慢。 模数较大还可以防止在没有仔细结构的情况下在值范围内进行幼稚的动态编程。 

一些边缘情况很容易出错。 如果数组已经是非递减的，则答案为零，因为不需要任何操作。 如果数组在包装意义上严格递减，例如`[m-1, 0, 1]`，它可能在本地看起来已损坏，但可能已经有效或需要仔细处理，因为模结构可能会产生误导。 当局部减少可以通过增加左侧或包裹右侧来“修复”时，就会出现另一个微妙的情况，而贪婪的选择如果不全局一致，很容易高估操作。 

## 方法

 蛮力观点是考虑为每个元素分配一个大于或等于前一个元素的最终值，同时考虑到每个增量操作都会均匀地移动位置的子集。 如果我们尝试直接模拟这一点，我们将重复扫描数组，查找违规行为，并一次一步地增加所选元素，直到数组排序。 每个完整通道可能仅修复一些冲突，并且在最坏的情况下，每个元素可能需要最多`m`增量。 这导致了复杂性的数量级`O(n * m)`或者更糟，它太大了。 

关键的结构观察是停止考虑个体增量，而是考虑每个位置总共必须增量多少次。 每个位置都会收到一定数量的增量，重要的是全局“轮数”的最小数量，以便我们可以在不违反非递减条件的情况下将这些增量分配给各个位置。 

假设我们从左到右处理数组，并决定每个元素必须有效接收多少增量，以便其最终值至少是前一个元素的最终值。 如果我们固定应用于前一个元素的增量数，我们可以计算当前元素所需的最小增量。 唯一的复杂性是环绕：从大值到小值可能需要一个完整的周期。 

这将问题转化为跟踪每个元素相对于其原始值必须提升多远，并确保相邻元素之间的一致性。 答案就是整个阵列所需的最大提升，因为一个操作对应于将一个单位的提升应用于选定的子集，并且我们需要足够的此类层来实现所需的最大提升深度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 模拟操作 | O(n·m) | O(n) | 太慢了 |
 | 贪婪增量提升| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们维护每个位置有效需要多少完整增量的概念，以便最终数组在线性解释时变得不递减。 

1. 从第一个元素开始，将其视为需要零个额外增量。 该元素设置基线，因为没有先前的约束。 
2. 对于每个下一个元素，在考虑前一个元素已经需要多少增量后，将其与前一个元素进行比较。 
3. 如果当前值已经大于或等于前一个调整值，则不需要“前绕”，因此其所需的增量深度与前一个保持一致。 
4. 如果当前值小于之前调整的值，则必须增大到至少达到之前的值。 这需要计算需要多少增量来弥补差距，并考虑模数。 
5. 跟踪所有元素所需的最大增量数。 该最大值表示所需的全局操作的最小数量，因为每个操作最多可以贡献一个增量层。 

最终的答案就是这个最大累计要求。 

### 为什么它有效

 每个元素所需的增量计数表示它必须包含在跨操作的选定子集中的次数。 因为每个操作都可以独立地递增任何子集，所以该过程相当于将增量堆叠起来。 非递减条件迫使这些层沿着数组是单调的，因为一旦提高值以满足先前的元素，后面的元素必须与该级别一致。 因此，所有位置所需的最大升力决定了所需的层数，并且子集选择的任何安排都不能减少到低于该最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    # dp-like variable: required "height" of increments so far
    cur = 0
    ans = 0
    
    for i in range(n):
        if i == 0:
            cur = 0
            ans = 0
            continue
        
        prev = a[i - 1] + cur
        
        if a[i] >= a[i - 1]:
            # no wrap conflict in raw values
            if a[i] < prev:
                # still need to match lifted previous
                add = (prev - a[i] + m - 1) // m
                cur += add * m
        else:
            # wrapped position, must jump over modulus boundary
            prev_mod = a[i - 1] + cur
            need = prev_mod - a[i]
            if need < 0:
                need = 0
            add = (need + m - 1) // m
            cur += add * m
        
        ans = max(ans, cur)
    
    print(ans)

if __name__ == "__main__":
    solve()
```该代码维护了一个运行概念，即通过模增量的完整周期，值已“提升”了多远。 变量`cur`跟踪迄今为止应用的累计向上移动，同时`ans`存储任意点所需的最大移位，这将成为最终答案。 

逻辑分割基于原始序列在相邻元素之间是增加还是减少，因为减少表示环绕边界。 在这两种情况下，我们确保当前元素足够高，以便在应用累积移位后，它不小于先前调整的元素。 每次校正可能需要多个完整的模周期，这些周期以倍数的形式相加`m`。 

一个微妙的点是，我们总是测量整个周期的调整，而不是单个增量，因为操作模型允许每次选择任意子集，所以重要的是全局层的数量，而不是每个元素的单独增量。

 ## 边缘情况

 一个重要的边缘情况是，数组看起来局部增加，但全局受到提升的先前值的约束。 例如，如果先前的元素已通过先前的修复有效地增加，则原始形式中数值较小的后续元素可能仍需要显着提升。 

另一种极端情况是出现多次连续下降。 每次减少都会增加所需的提升水平，而忽略累积效应会导致计数不足。 

第三种情况是当值接近模数边界时。 忽略环绕的天真比较将错误地假设不需要校正，而实际上需要完整的周期调整才能在累积升力下保持排序。
