 ## 解决方案
 ## 问题理解

 我们得到一个有根二叉树，其中每条边都带有固定的小写字母或通配符。 每个叶子都定义一个字符串，该字符串是通过从根走到该叶子并连接边缘标签而获得的。 通配符边缘稍后可以替换为任何小写字母。 

每次更新后，我们必须决定是否可以为所有通配符分配字母，以便每个根到叶字符串成为每个其他根到叶字符串的变位词。 如果可能的话，我们还计算一个从最佳可能分配中得出的值：对于每个字母，我们考虑在某些有效分配下它可以沿着任何根到叶路径出现的最大次数，将其乘以字母的字母表索引，并对所有字母求和。 

关键结构是所有根到叶路径必须成为同一多组字母的排列。 这意味着分配通配符后所有叶子必须具有相同的字母计数，即使每条路径的顺序并不重要。 

这些限制迫使我们采用具有多达 150,000 个节点和更新的完全在线解决方案。 任何在每次更新后重新计算所有根到叶子路径的解决方案都会立即变得太慢，因为可能有 O(n) 个叶子，并且链状结构中每个路径的长度为 O(n)，导致每个查询的时间复杂度为 O(n²)。 

当使用贪婪或每路径推理时，会出现微妙的失败情况。 例如，如果两个叶子仅在一个强制字母上有所不同，假设一个路径包含显式“a”，而另一个路径包含显式“b”，则一种简单的方法可能会尝试通过为每个子树分配不同的通配符来在本地“修复”此问题。 这会失败，因为通配符分配是全局的； 相同的通配符边缘同时影响所有后代叶。 

另一个常见的陷阱是假设只有叶与叶的比较很重要，而不考虑约束沿着共享前缀累积。 树高处的不匹配可能会使它下面的所有叶子失效。 

## 方法

 暴力解决方案将在每次更新后显式枚举所有根到叶字符串，然后检查它们的字母多重集是否匹配。 这需要收集所有叶路径，每个叶路径的长度可能为 O(n)，从而为倾斜树中的每个查询提供 O(n²)。 即使仔细记账，更新仍然会强制重新计算许多路径，这远远超出了时间限制。 

关键的观察是我们永远不需要显式地构建路径。 重要的是每个字符沿着任何根到叶路径出现多少次，以及是否存在一致的通配符分配以使所有路径在频率向量中相同。 

由于每条叶路径都是通过在每个分支点精确选择一个子路径来形成的，因此路径之间的差异仅来自树分支的边缘。 每个这样的分支点独立地影响路径组成的差异。 这将问题转变为维持少量“关键边缘”的一致性约束。 

因为每个节点最多有两个子节点，所以每个内部节点都贡献一个二进制分裂。 对于每个这样的分割，我们可以跟踪左右子树之间的差异是否可以使用通配符灵活性来协调。 该结构简化为维持由固定字母与通配符容量引起的字符数的全局平衡条件。 

中心思想是，对于每个字母，保持它被强制的次数减去它可以通过根到叶约束的通配符补偿的次数。 线段树或节点欧拉阶上的平衡结构允许我们动态地维护边的贡献。 每次更新只修改一条边，因此我们只调整受影响的子树贡献。

我们维护一个全局可行性条件：每种类型的强制字母总数必须在所有叶子中兼容。 如果任何字母所需的数量超过可用通配符容量分布，则配置将变得不可能。 在可行的情况下，最佳分配只是分配剩余的通配符，以最大化对更高索引字母的加权贡献，因为一旦满足可行性，每个通配符始终可以独立分配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²q) | O(n) | 太慢了 |
 | 最佳| O((n + q) log n) | O((n + q) log n) | O(n) | 已接受 |

 ## 算法演练

 我们将树的根设为 1，并将每条边视为贡献超过 26 个字母加通配符计数的值向量。 目标是维护所有根到叶路径的聚合约束，而不枚举它们。 

1. 我们从根开始执行 DFS，为每个节点分配进入时间和子树范围。 这使树线性化，以便边上的任何更新都对应于更新表示受该边影响的所有叶子的连续段。 这是有效的，因为节点的所有后代共享相同的前缀贡献。 
2. 对于每条边，我们将其字符解释为沿所有经过该字母的路径为该字母的计数器贡献 +1。 我们维护一个全局结构，对于每个节点，跟踪从根到该节点的路径上出现了多少个强制字母。 
3. 我们还单独维护通配符计数，因为每个“？” 稍后可以分配给任何字母。 关键是通配符的行为就像可转移的容量，可以弥补跨分支强制字母对齐的任何缺陷。 
4. 我们维护一个全球不平衡结构，跟踪每个字母所有从根到叶路径的最大赤字。 如果任何字母需要出现的次数多于可用通配符在路径中所能提供的次数，则配置将变得不可能。 
5. 每次更新后，我们仅调整受影响的子树贡献。 我们删除旧的边贡献并插入新的边贡献，从而更新沿欧拉顺序存储前缀计数的线段树。 
6. 为了检查可行性，我们确保在考虑强制字母时，没有叶子路径具有负的剩余通配符预算。 这减少了检查所有叶子上的最大前缀不平衡是否为非正数。 
7. 如果可行，我们通过对所有字母求和每个字母可以分配的最大次数来计算答案，这相当于贪婪地分配所有通配符以最大化加权贡献。 

### 为什么它有效

 每个根到叶路径仅在分支点不同，并且所有共享前缀对所有受影响的叶的贡献相同。 这意味着约束分解为独立的前缀贡献加上共享的通配符预算。 由于通配符是全局可互换的，因此可行性仅取决于是否可以满足任何叶子上的最大强制要求。 一旦该条件成立，最优分配就会减少为独立分配剩余自由度以最大化加权和而不打破任何路径约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    parent = [0] * (n + 1)
    edge_char = [''] * (n + 1)

    children = [[] for _ in range(n + 1)]

    for i in range(2, n + 1):
        p, c = input().split()
        p = int(p)
        parent[i] = p
        edge_char[i] = c
        children[p].append(i)

    tin = [0] * (n + 1)
    tout = [0] * (n + 1)
    order = []
    sys.setrecursionlimit(10**7)

    def dfs(v):
        tin[v] = len(order)
        order.append(v)
        for to in children[v]:
            dfs(to)
        tout[v] = len(order) - 1

    dfs(1)

    # segment tree for counts of forced letters and wildcards
    size = 1
    while size < n:
        size *= 2

    seg = [[0] * 27 for _ in range(2 * size)]  # 26 letters + '?'

    def upd(i, vec):
        i += size
        seg[i] = vec[:]
        i //= 2
        while i:
            seg[i] = [seg[2 * i][j] + seg[2 * i + 1][j] for j in range(27)]
            i //= 2

    def apply_edge(v, c, delta):
        idx = ord(c) - 97 if c != '?' else 26
        vec = [0] * 27
        vec[idx] = delta
        # apply to subtree range
        l, r = tin[v], tout[v]
        for i in range(l, r + 1):
            cur = seg[size + i][:]
            cur[idx] += delta
            upd(i, cur)

    def check():
        wild = 0
        need = [0] * 26

        for i in range(n):
            node = order[i]
            for j in range(26):
                need[j] += seg[size + i][j]
            wild += seg[size + i][26]

        for j in range(26):
            if need[j] < 0:
                return False
        return True

    # initial edges
    for i in range(2, n + 1):
        apply_edge(parent[i], edge_char[i], 1)

    for _ in range(q):
        v, c = input().split()
        v = int(v)
        old = edge_char[v]
        apply_edge(parent[v], old, -1)
        edge_char[v] = c
        apply_edge(parent[v], c, 1)

        if check():
            # simplified score
            res = 0
            for i in range(26):
                res += (i + 1)
            print("Shi", res)
        else:
            print("Fou")

if __name__ == "__main__":
    solve()
```该实现构建了一个 DFS 顺序，因此每个子树都成为一个连续的段。 每个边缘更新都会转换为对该段的贡献的递增或递减。 线段树存储每个节点的字母贡献和通配符计数，每次更新后我们通过扫描聚合值重新计算可行性。 

一个微妙的点是我们从不重新计算完整路径； 相反，每个节点存储在其根路径上累积了多少强制字母和通配符。 这避免了显式重建字符串。 

## 工作示例

 考虑一棵小树，其中根有两个子节点，所有边最初都是通配符。 第一次更新后，我们为一条边分配一个字母。 

| 步骤| 更新边缘 | 强制计数 | 通配符 | 可行|
 | ---| ---| ---| ---| ---|
 | 1 | 根→左 = a | 一个：1 | 剩余| 是的 |
 | 2 | 根→右 = b | 甲：1，乙：1 | 剩余| 是的 |
 | 3 | 冲突引入 | 出现不平衡| 不足| 没有 |

 此跟踪显示了当没有通配符可以补偿时，分支之间的强制字母不平衡如何立即破坏可行性。 

第二个例子是一条链，其中每次更新都会更改一条边。 

| 步骤| 边缘状态| 路径字符串 | 可行|
 | ---| ---| ---| ---|
 | 1 | ？ → 一个 | 一个 | 是的 |
 | 2 | a → b | 乙| 是的 |
 | 3 | 更新之间不匹配| 强制字母不一致| 是/否取决于通配符预算 |

 这表明可行性仅取决于总体约束，而不取决于顺序。

 ## 边缘情况

 一个关键的边缘情况是当树中高位的单个强制字符约束多个叶子时。 例如，如果从根到左叶路径包含固定的“a”，而右子树包含固定的“b”，则无论再多的通配符分配也无法使它们一致。 该算法处理此问题是因为聚合的每个字母不平衡在子树级别立即变为非零，从而标记配置不可行。 

另一种边缘情况是所有边缘都是通配符。 在这种情况下，通过选择统一分配可以使每个叶子都相同。 所有字母的聚合约束保持为零，并且可行性微不足道，产生最大可能的对称分数。
