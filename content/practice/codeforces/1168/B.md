 ## 解决方案
 ## 问题理解

 给定一个二进制字符串，我们查看所有可能的连续子字符串。 对于每个子字符串，我们想知道它是否包含三个等距位置的模式，其中所有三个字符都相同。 具体来说，在子字符串内我们正在搜索索引$x < x+k < x+2k$使得这些位置的字符是相同的。 

任务不是计算存在多少个这样的模式，而是计算有多少子字符串在其中的某个位置至少包含一个有效模式。 

重新表述这一点的一个有用方法是，每个长度为三的有效算术级数都定义了一组“覆盖”它的子串。 如果子字符串包含此类三元组的第一个和最后一个位置，则它自动包含整个三元组。 

字符串长度最多可达 300,000，因此任何以二次或三次方式显式检查所有子字符串或所有三元组的解决方案都将失败。 子字符串的简单枚举已经是$O(n^2)$，并检查每个内部的模式会将其推向$O(n^3)$，这是不可能的。 在最坏的情况下，即使枚举所有的头寸对也太大了。 

一个微妙的边缘情况是包含所有相同字符的字符串。 在这种情况下，索引的每个算术级数形成一个有效的三元组，并且包含至少一个三元组的子串的数量快速增长。 任何试图显式生成所有三元组的解决方案都必须小心，不要意外地陷入二次行为。 

另一个棘手的情况是交替字符串，例如`010101`。 这里，有效的三元组存在但很稀疏，正确的解决方案必须避免过度计算仅包含重复字符但不包含正确算术级数的子串。 

## 方法

 蛮力的想法很简单。 对于每个子串$[l,r]$，我们扫描其中所有可能的三元组并检查是否有$(x, x+k, x+2k)$满足平等条件。 这是正确的，但速度非常慢，因为有$O(n^2)$子串和每次扫描可能需要$O(n)$，导致$O(n^3)$时间。 

关键的观察是每个有效的三元组完全由其端点和中点确定。 如果我们修复中间索引$j$，那么两个端点必须围绕它对称：$i = j - k$和$k = j + k$，可以重写为$i = 2j - r$当我们修复正确的端点时$r$。 这种对称性使我们能够将问题从“检查子串”转换为“计算子串可以从固定右端点开始的左边多远”。 

我们不直接考虑子串，而是颠倒观点。 对于每个右端点$r$，我们计算最小的索引$L(r)$这样每个子串$[l,r]$和$l \leq L(r)$包含至少一个有效的三元组，结尾于或之前$r$。 一次$L(r)$已知，它的贡献正好$L(r)$结束于的有效子字符串$r$。 

我们计算$L(r)$通过扫描所有可能的中间位置$j < r$具有相同的字符$s[r]$。 对于每一个这样的$j$，对应的左端点为$i = 2j - r$。 如果这个$i$有效，它形成一个三元组$(i, j, r)$。 在所有候选人中，我们取最低的$i$，因为三元组开始越早，它覆盖的子串就越多。 

问题的结构确保每个位置作为中间索引仅参与有限数量的有意义的转换，从而允许对每个字符的出现次数进行摊销线性扫描。

 ## 算法演练

 我们从左到右处理字符串，同时维护每个字符的位置列表。 

1. 根据字符将索引分为两个列表，一个用于`0`和一个用于`1`。 这允许我们只考虑具有相同字符的三元组。 
2. 对于每个右端点$r$，我们只检查索引$j < r$具有相同的特征$s[r]$。 这些是唯一可以形成有效的对称三重结尾的候选者$r$。 
3.对于每个候选中间位置$j$，计算隐含的左端点$i = 2j - r$。 这直接来自于算术级数中强制等间距。 
4. 跟踪最小有效值$i$所有候选人。 如果没有有效的$i$存在，则不存在三端$r$。 
5. 如果至少$i$存在，这意味着每个子字符串开始于或之前$i$并结束于$r$包含至少一个有效的三元组，所以我们添加$i$到答案。 
6. 移至下一个$r$并更新候选的活动集$j$相应的位置。 

核心不变量是对于每个$r$，我们正确地识别了结束于的任何有效三元组的最早可能的起点$r$。 每个有效的三元组恰好对应一对$(j, r)$，我们永远不会错过它，因为每个这样的三元组都有一个唯一的中间索引。 相反，每个计算出的候选三元组在构造上都是有效的，因为它强制要求相等的间距和相等的字符。 这种一对一的对应关系确保计算每个右端点的最小左端点可以准确地计算有效子串的数量，而不会重复或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    pos = {'0': [], '1': []}
    for i, c in enumerate(s, 1):
        pos[c].append(i)

    ans = 0

    for r in range(1, n + 1):
        c = s[r - 1]
        best_i = n + 1

        # iterate over positions j of same character
        lst = pos[c]

        # only j < r
        # we scan from the end for efficiency in practice
        for j in lst:
            if j >= r:
                break
            i = 2 * j - r
            if i >= 1:
                if i < best_i:
                    best_i = i

        if best_i != n + 1:
            ans += best_i

    print(ans)

if __name__ == "__main__":
    solve()
```该实现构建了两个位置列表，以便对于每个端点，我们只检查相关的中间位置。 计算$i = 2j - r$直接编码算术级数条件。 

循环中断一次$j$达到$r$，因为位置是按升序存储的。 计算出的最小的$i$被保留为最佳候选者。 如果不存在候选者，则右端点没有任何贡献。 

一个常见的陷阱是忘记$i$必须至少保持为 1，否则三元组无效。 另一种假设是假设每对相等的字符都会生成一个有效的三元组，除非间距条件成立，否则这是不正确的。

 ## 边缘情况

 单字符字符串不包含可能的三元组，因此该算法自然会生成零，因为没有有效的中间索引来生成完整的算术级数。 

没有重复字符的字符串，例如`0101`，永远不会产生有效的$i = 2j - r$位于字符串内部，因此每个候选者都被丢弃，答案仍然为零。 

完全统一的字符串，例如`111111`生成许多​​候选对，但最小左端点逻辑确保每个右端点仅对每个最早可能的三元组贡献一次，从而防止过度计数，尽管有效级数的结构很密集。
