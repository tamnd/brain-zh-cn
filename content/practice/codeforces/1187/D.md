 ## 解决方案
 ## 问题理解

 我们得到两个长度相等的数组，并允许重复选取第一个数组的任何连续段，并仅以非递减顺序对该段进行排序。 经过多次这样的操作后，我们想知道是否可以将初始数组准确地转换为目标数组。 

关键细节是每个操作不会任意移动元素，它只允许在选定的间隔内进行本地重新排序。 然而，由于间隔可以重叠并自适应地选择，因此该过程可以模拟相当复杂的重新排列，只要它们与重复分段排序可以实现的效果一致即可。 

所有测试用例的总长度最多为 300,000 的约束意味着每个测试的任何解决方案都必须接近线性或线性算数。 每次测试任何二次方都是不可能的，因为即使是一个大小为 200,000 的最坏情况数组也已经超出了时间限制。 

当从左到右贪婪地推理而不跟踪全局可行性时，会出现微妙的失败模式。 例如，如果我们尝试独立匹配位置，我们可能会错误地认为我们总是可以在本地“修复”不匹配。 

考虑这样一种情况：目标数组早期所需的值仅出现在源数组较晚的位置。 天真的贪婪者可能会说我们可以对覆盖它的段进行排序，但是该段排序还会拖入中间元素，这些元素可能会破坏先前固定的位置。 这种耦合是核心难点。 

## 方法

 蛮力视角是模拟这个过程：在所有可能的序列中尝试所有可能的子数组排序，并检查是否可以到达目标数组。 每个操作都会改变数组状态，在最坏的情况下，我们将探索每步 O(n²) 个选择的巨大分支因子，甚至可能是 O(n) 个步骤，这在组合上是爆炸性的。 

即使是稍微聪明一点的暴力尝试对数组状态进行 BFS 也会立即失败，因为可达排列的数量增长得非常快。 该操作足够强大，可以生成许多中间配置，因此状态空间爆炸使得直接模拟变得不可能。 

关键的见解是扭转观点。 我们不是问是否可以将 a 转换为 b，而是问是否存在一种一致的方法将 a 的元素“分配”到 b 中的位置，限制条件是排序段仅允许我们逐渐重新排序元素，但决不会违反沿前缀的多重集可行性。 

这导致了一个前缀可行性条件：当我们从左到右扫描时，每当我们决定b中的位置i必须出现什么值时，我们必须确保到a中的那个点我们已经看到足够的元素来支持它。 然而，由于段排序可以在任何间隔内重新排序，所以正确的抽象是，只要我们尊重相对可用性约束，我们就可以获取可用元素并重新排列它们。 

对此进行编码的一种简洁方法是模拟值的处理，同时维护由我们被迫匹配 b 的位置引起的多组“活动段”。 经典的解决方案将问题简化为检查我们是否可以贪婪地分配元素，同时尊重我们只能延迟元素，而不能发明或销毁它们。 

同样，我们可以处理数组并维护不匹配元素的计数，确保在每个前缀处，a 中的元素多重集足以覆盖 b 所需的多重集（直到该前缀），并通过段排序结构强制执行排序约束。

一个更易于实现的解释是，当且仅当我们从左到右扫描时，我们总是可以将 b[i] 与 a[j] 的某些出现相匹配，而该 a[j] 没有被先前固定的结构“阻止”，该过程是可能的，可以使用类似堆栈的结构在相等约束的段上进行维护。 

这减少了对动态形成的段内频率的贪婪一致性检查，这可以在每次测试的线性时间内完成。

 ## 算法演练

 关键的观察是，唯一真正的约束来自分段排序如何合并和重新排序连续的未解析区域。 我们通过维护一个结构来模拟该过程，该结构代表我们已经看到但尚未在最终安排中提交的元素。 

我们从左到右处理数组，维护 a 中可用元素的类似多重集的结构，并在每一步与 b 所需的元素进行比较。 然而，我们也必须尊重元素可以跨段延迟，这相当于只要不违反可行性就允许临时缓冲。 

1. 我们从左到右迭代位置，将每个位置视为 b 施加的要求。 
2. 我们维护一个结构，表示 a 中已遇到但尚未分配到 b 中固定位置的元素。 
3. 每次我们在 a 中前进时，我们都会将新元素添加到该池中，因为它可用于将来的放置。 
4. 当我们到达 b 中的位置 i 时，我们检查所需的值 b[i] 当前在池中是否可用。 
5. 如果可用，我们将其分配并将其从池中删除，因为我们可以使用段排序操作最终将其放置到位。 
6. 如果不可用，我们立即断定这是不可能的，因为未来的操作都不会创建缺失值。 
7. 我们继续此过程，直到处理完所有位置。 

微妙的一点是为什么这个贪心赋值是有效的。 分段排序确保一旦某个值出现在当前可达前缀池中，我们总是可以在某个间隔内重新排列，将其带到正确的位置，而不会干扰已经固定的早期匹配，因为未解析的区域始终可以联合排序以调整内部排序。 

### 为什么它有效

 在任何前缀处，该算法都认为 b 中的每个指定值都与 a 中的不同出现匹配，该出现不晚于需要它的点。 由于段排序允许在任何选定的间隔内进行任意重新排序，因此可以在活动区域​​内自由排列任何可用元素集。 这意味着唯一的约束是前缀的多重性，而不是精确的位置结构。 如果在任何时候可用池中缺少所需的元素，则任何段排序序列都无法引入它，因此失败是不可避免的。 相反，如果所有要求都能按顺序满足，我们总是可以通过对覆盖未解析后缀的段进行逐步排序来实现排列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import defaultdict, deque

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        # We use a multiset-like structure via deque lists per value
        pos = defaultdict(deque)
        for i, x in enumerate(a):
            pos[x].append(i)

        # We simulate consumption of positions in increasing order
        # using a pointer over "time" in a
        available = defaultdict(int)

        ptr = 0
        ok = True

        # We maintain a moving pointer and mark consumed occurrences
        used = [False] * n

        for i in range(n):
            need = b[i]

            # expand until we can satisfy need
            while ptr < n and available[need] == 0:
                x = a[ptr]
                available[x] += 1
                ptr += 1

            if available[need] == 0:
                ok = False
                break

            available[need] -= 1

        out.append("YES" if ok else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现维护数组 a 上的指针并逐渐扩大可用元素集。 字典`available`计算每个值中有多少我们仍然可以使用。 对于 b 中的每个所需值，我们扩展 a 的前缀直到该值出现，然后使用它。 

重要的实现细节是我们永远不会倒回 a 中的指针。 这编码了这样一个事实：一旦通过考虑前缀来暴露元素，它们仍然可用于将来通过段排序进行的任何重新排列，因此我们只需要单调扩展。

 ## 边缘情况

 临界边缘情况是 b 需要一个出现在 a 中但仅在长前缀之后的值。 该算法正确地扩展 ptr 直到该值可用，从而确保不会过早失败。 

另一个边缘情况是重复值，其中必须按顺序匹配多个相同的元素。 基于频率的消耗确保了重复项被独立处理，因此当多次需要相同的值时不会发生错误拒绝。 

最后的边缘情况是 b 是可全局排序但不可通过段约束局部构造的排列。 贪婪前缀扩展可以正确识别所需元素何时尚未公开，从而防止无效的早期分配。
