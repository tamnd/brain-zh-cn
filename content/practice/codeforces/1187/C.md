 ## 解决方案
 ## 问题理解

 我们被要求构造任意长度的整数数组$n$这与关于子数组的一组约束是一致的。 每个约束都描述了一个段必须是非递减的，或者它必须不能是非递减的。 

标记为“已排序”的段会强制其中的每个相邻对满足$a_i \le a_{i+1}$。 标记为“未排序”的段仅要求其内部至少存在一个相邻的反转，这意味着某些$a_j > a_{j+1}$在那个区间内。 挑战在于数组本身并未给出，仅给出了重叠间隔上的这些关系约束。 

关键的困难在于“排序”约束是全局的、刚性的，而“未排序”的约束是存在的、局部的。 有效的构造必须满足所有单调要求，同时仍然在每个禁止间隔内放置至少一个下降。 

限制条件$n, m \le 1000$允许$O(n^2)$或者$O(nm)$通过预处理或传播进行构造，但是任何需要枚举所有数组或检查所有分配的操作都是不可行的。 我们显然处于一个建设性或贪婪的政权中，我们逐步加强结构。 

当“未排序”段完全包含在因“已排序”约束而强制不减少的区域内时，就会出现微妙的边缘情况。 在这种情况下，答案立即是不可能的，因为单调性禁止该区域任何地方的任何下降。 例如，如果我们被告知$(1, 1, 5)$还有$(0, 2, 3)$，那么第二个约束是不可能的，因为第一个约束强制所有邻接$[1,5]$为非递减。 

另一个微妙的情况是重叠的排序段，这些段共同强制一个大联合的全局单调性，使得不可能放置所需的下降，除非它位于所有强制区域之外。 

## 方法

 一个天真的想法是将数组视为未知数组，并尝试相邻元素之间的所有可能的不等式分配，决定每对是否$a_i \le a_{i+1}$或者$a_i > a_{i+1}$。 一旦这些决定被确定，我们就可以分配与它们一致的实际数值。 

然而，这是指数级的$n$，因为每个$n-1$邻接关系可以是增加的，也可以是减少的。 即使我们只考虑一致性检查，每个分配都需要验证所有$m$约束、给予$O(2^n \cdot nm)$，这远远超出了限制。 

关键的观察是，唯一重要的真实结构是我们被允许放置减少的地方。 如果我们决定由于类型 1 约束而某些邻接必须是非递减的，则任何类型 0 约束必须至少包含此强制集合之外的一个邻接。 这将问题重新构建为构建一组“禁止的相等边”，并确保每个“未排序”间隔至少包含一个允许严格丢弃的边。 

这表明了一种贪婪的构造：我们首先假设所有邻接都是非递减的，然后有选择地引入严格递减以满足所有类型 0 约束。 由于类型 1 约束禁止在某些范围内减少，因此我们必须确保任何选定的减少位置都在所有这些禁止区间之外。 

最后一步是分配实际值：我们可以简单地从一个大值开始，然后根据是否放置中断或使用分段标签来减少或维持值。

 ## 算法演练

 我们将问题转化为决定哪些相邻位置$i \to i+1$会严格滴。 让我们称这些为“断点”。 

1. 首先假设所有相邻对都是非递减的，这意味着我们最初没有设置强制中断。 
2. 处理所有类型1 约束。 对于每个段$[l, r]$，我们标记每个邻接$l \le i < r$必须是非减的。 实际上，这意味着我们不允许在任何这些段内放置断点。 
3. 根据类型 1 约束，我们构建了一组禁止的边，其中不允许中断。 任何有效的断点必须位于所有这些强制单调区域之外。 
4. 现在处理 0 类约束。 对于每个间隔$[l, r]$，我们至少需要一个断点$i$和$l \le i < r$这并没有被禁止。 如果不存在这样的位置，那么就不可能立即给出答案。 
5. 为了有效地保证这一点，我们贪婪地选择断点位置。 我们迭代所有位置，每当遇到尚未满足的 0 型区间时，只要不被禁止，我们就会在其中最右边可能的有效位置放置一个断点。 这确保了未来的约束不会受到不必要的伤害。 
6. 确定所有断点后，构造数组。 我们从左到右分配值。 从一个大数字开始并设置$a_1 = 10^9$。 对于每个$i$，如果位置$i$是一个断点，设置$a_{i+1} = a_i - 1$。 否则设置$a_{i+1} = a_i$。 

这样做的原因是，相等的相邻值对非递减段进行编码，而严格减少对保证违规进行编码。 因为每个 0 型区间至少包含一个强制减少，所以保证不会被排序，并且因为在任何禁止区域内都没有放置中断，所以所有 1 型约束仍然有效。 

保持的不变性是，在处理每个约束之后，到目前为止看到的每个 0 型区间至少包含一个选定的断点，并且没有断点位于任何 1 型强制单调段内。 这可以防止冲突错误地累积。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    # forbidden[i] means we cannot place a "decrease" between i and i+1
    forbidden = [False] * (n + 1)

    type0 = []
    
    # First process type 1 constraints: forbid decreases inside them
    for _ in range(m):
        t, l, r = map(int, input().split())
        if t == 1:
            for i in range(l, r):
                forbidden[i] = True
        else:
            type0.append((l, r))

    # Try to place breaks greedily for type 0 constraints
    break_at = [False] * (n + 1)

    for l, r in type0:
        found = False
        # try to place a break as right as possible
        for i in range(r - 1, l - 1, -1):
            if not forbidden[i]:
                break_at[i] = True
                found = True
                break
        if not found:
            print("NO")
            return

    # construct array
    a = [0] * (n + 1)
    a[1] = 10**9

    for i in range(1, n):
        if break_at[i]:
            a[i + 1] = a[i] - 1
        else:
            a[i + 1] = a[i]

    print("YES")
    print(*a[1:])

if __name__ == "__main__":
    solve()
```该代码首先将所有类型 1 约束转换为禁止的邻接位置，这意味着这些边必须保持非递减。 然后，它通过在每个间隔内从右向左扫描并在最新的可能有效位置放置一个断点，确保每个 0 型间隔至少有一个选定的断点。 最后，它通过从左到右传播值来构造一个具体数组，仅在选定的断点处递减。 

一个微妙的实现细节是我们存储每个邻接的断点，而不是在约束处理期间直接修改值。 这种分离避免了重叠约束之间的意外相互作用，并确保可行性检查独立于数字分配。

 ### 示例 1

 输入：```
7 4
1 1 3
1 2 5
0 5 6
1 6 7
```我们首先禁止类型 1 段中的中断。 

| 步骤| 约束| 禁止边缘| 选择的休息时间 |
 | ---| ---| ---| ---|
 | 1 | [1,3] 已排序 | 1-2, 2-3 | 无 |
 | 2 | [2,5] 已排序 | 2-3、3-4、4-5 | 到目前为止还没有 |

 | 4 | [6,7] 已排序 | 6 | 无 |

 开始$a_1 = 10^9$。 我们保持相等直到索引 5，然后在 5 处减小，然后再次保持相等。 这会产生一个匹配所有约束的有效数组。 

该跟踪显示了如何在尊重单调区域的同时独立满足 0 型约束。

 ## 边缘情况

 当 1 类约束覆盖整个数组时，就会出现一种边缘情况。 在这种情况下，所有相邻位置都禁止中断，因此任何类型 0 约束立即变得不可能。 该算法处理此问题是因为内部扫描无法找到任何有效的断点并返回 NO。 

当多个 0 型间隔严重重叠但所有间隔均由单个断点满足时，会出现另一种边缘情况。 贪心策略自然会处理这个问题，因为一旦放置断点，覆盖该索引的所有区间都将隐式满足，并且不需要额外的工作。 

最后一种微妙的情况是，当约束迫使允许断点形成“紧密走廊”时，例如只有一个邻接保持空闲。 该算法仍然成功，因为它总是尝试最右边的有效位置，确保以最大化未来约束覆盖范围的方式使用有限的灵活性。
