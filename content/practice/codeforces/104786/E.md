 ## 解决方案
 ## 问题理解

 我们得到了大小的排列$n$，表示从 1 到的每个整数$n$恰好出现一次。 对于每对索引$(l, r)$，我们查看数组的片段$l$到$r$。 我们只想计算端点处的值的那些段，$p_l$和$p_r$，已经“控制”了整个段：段内的每个元素都必须位于两个端点中较小和较大的端点之间。 

换句话说，如果我们取两个端点的最小值和最大值，它们之间的整个子数组必须保持在该数字区间内。 段中的任何元素都不允许超出端点定义的范围。 

天真的解释是考虑每个段并验证是否有任何元素违反端点边界。 和$n$最多$5 \cdot 10^5$，大约有$2.5 \cdot 10^{11}$段，甚至在线性时间内检查每个段都是不可能的。 甚至一个$O(n^2)$方法已经太大了。 

一个微妙的点是，条件仅取决于端点处的极值，但它仍然约束所有内部元素。 这暗示我们实际上正在计算端点“足够极端”的段，因此没有中间元素逃脱其值区间。 

一个幼稚的陷阱是假设只有相邻或单调的​​片段才重要。 例如，在类似的排列中$1\ 3\ 2\ 4\ 5$, 段$(1,5)$即使它不是单调的，也是有效的，因为所有内部值都在 1 到 5 之间。另一方面，$(2,4)$如果某些内部值超出端点范围，则可能会失败。 

困难是全局性的：每个段都取决于所有中间值，因此我们需要一种方法来避免重新计算每对的最小值和最大值。 

## 方法

 暴力解决方案很简单。 对于每对$(l, r)$，计算子数组中的最小值和最大值$p[l:r]$或扫描该段并检查是否有任何元素位于外部$[\min(p_l, p_r), \max(p_l, p_r)]$。 这是有效的，因为它直接验证条件，但它需要$O(n^3)$如果天真地重新计算极值或$O(n^2)$如果我们维持每个启动索引的运行最小值和最大值。 和$n = 5 \cdot 10^5$， 甚至$O(n^2)$导致大约$2.5 \cdot 10^{11}$操作，远远超出任何限制。 

关键的观察是将视角从端点定义的片段转移到充当障碍的元素。 修复一个端点，例如$l$。 随着我们的扩展$r$向外，该段是有效的，直到我们遇到一个超出由定义的范围的值$p_l$和$p_r$。 问题是范围本身随着$r$，所以这仍然感觉是循环的。 

如果我们根据中间元素施加的排序约束来思考，真实的结构就会变得更加清晰。 一段$(l, r)$如果存在某个索引则无效$i \in (l, r)$这样$p_i < \min(p_l, p_r)$或者$p_i > \max(p_l, p_r)$。 这意味着每个内部元素必须被间隔端点“覆盖”。 

这相当于说，对于每个内部位置，端点值必须跨越值空间中的它。 每个内部元素有效地禁止某些端点对：如果内部值非常小或非常大，它会限制哪些端点可以在其周围形成有效对。 

重新构建这一点的一种有效方法是按价值递增的顺序处理职位。 当我们固定一个值时$x$，它将约束索引空间中“跨越它”的对。 具体来说，如果我们知道所有值小于或大于$x$谎言，我们可以确定有多少对在两边都有端点$x$，这将违反有效性，除非$x$位于端点值之内。 

这导致了一个经典的反转式计数思想：每个元素对无效对的贡献取决于其两侧有多少个较小/较大的元素。 我们不检查段，而是计算有多少个三元组$(l, r, i)$造成违规并从总对中减去。 

总索引对是$n(n+1)/2$。 如果存在位于端点范围之外的内部点，则对是无效的，可以通过充当以禁止方式穿过它的对的“分隔符”的每个元素来计数该内部点。 通过跟踪 Fenwick 树（或 BIT）中的位置，我们可以维护每一侧已看到的值数量并有效地计算贡献。 

最终的解决方案简化为按顺序处理值，并计算它们相对于其位置创建的反转次数，每个元素的贡献基于其左侧和右侧有多少已处理的元素。

 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了 |
 | 最佳 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们按照值的递增顺序处理排列，将每个值视为它变得“活跃”的那一刻。 

1. 将每个值放置在其位置并维护一个数据结构来跟踪哪些位置已被激活。 最初没有活跃的职位。 这可以让我们随时知道哪些值小于当前值并且已被处理。 
2. 处理值时$x$在位置$pos[x]$，我们将其插入索引上的 Fenwick 树中。 这种结构使我们能够有效地计算有多少已插入的位置位于任何索引的左侧或右侧。 
3. 对于当前位置$pos[x]$，计算有多少个之前处理过的位置在左边，有多少在右边。 让这些成为$L$和$R$。 这些对应于小于的值$x$已经放置在这些区域。 
4. 引入的新无效对的数量$x$是$L \cdot R$。 这是因为在左侧选择一个较小的元素，在右侧选择一个较小的元素，形成夹在中间的端点$x$在他们的范围之外。 
5. 在所有值上累积这些贡献。 无效配置的总数是所有此类产品的总和。 
6. 通过获取指数对总数并减去无效贡献来转换为最终答案。 

### 为什么它有效

 每个元素$x$充当端点位于其位置相对侧的对的唯一最小或最大障碍。 如果端点跨越$x$按索引顺序但是$x$不在它们之间按值顺序排列，则条件对于该对仅失败一次。 由于值是按升序处理的，因此每个此类违规都准确地归因于跨度内打破端点间隔的最小元素。 这可确保不会重复计算任何对，也不会遗漏无效的对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

n = int(input())
p = list(map(int, input().split()))

pos = [0] * (n + 1)
for i, v in enumerate(p, 1):
    pos[v] = i

fw = Fenwick(n)

ans = 0

for v in range(1, n + 1):
    i = pos[v]
    left = fw.sum(i - 1)
    right = fw.sum(n) - fw.sum(i)
    ans += left * right
    fw.add(i, 1)

total_pairs = n * (n + 1) // 2
print(total_pairs - ans)
```芬威克树维护已经放置了多少个小于当前值的值。 在每一步中，当前值的贡献取决于其左侧和右侧有多少个这样的较小值，因为这些较小值形成端点对，这些端点对将不满足条件，而该值充当内部违规点。 

最后的减法步骤将计算出的无效计数转换为所需的有效段数。

 ## 边缘情况

 对于单元素排列，唯一有效的段是$(1,1)$。 该算法插入第一个值，发现没有左或右贡献，然后输出$1$从总数中减去零个无效对后。 

对于完全递增或递减的排列，在处理过程中，任何值的两侧都不具有较小的元素，因此每个贡献都保持为零。 结果就变成完整的$n(n+1)/2$，符合单调结构下每个段都有效的事实。
