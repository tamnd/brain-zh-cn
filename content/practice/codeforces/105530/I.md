 ## 解决方案
 ## 问题理解

 我们得到一个字符串，然后重复执行删除连续段的操作。 每次删除都会删除一个子字符串，删除后，剩余的字符会折叠在一起，就像字符串被重新索引一样。 

一个关键的结构观察是，如果我们删除了完全位于另一个段内的段，那么较小的删除就是多余的。 我们可以一步删除较大的间隔，而不是先删除一个小间隔然后再扩展它。 这意味着最佳策略可以被视为选择一系列不重叠的删除，从而有效地将过程划分为独立的阶段。 

重新构建这一点，任务就变成寻找一种方法将字符串分解为最少数量的段，以便每个段都有一个特定的“好”结构，允许以最佳方式删除它。 编辑见解告诉我们，这种结构简化为：在每个处理的段中，最左边和最右边的字符必须匹配，因为任何有效的删除始终可以向外扩展到最近的等字符边界，而不会增加操作数量。 

输入是单个字符串，输出是在此规则下删除整个字符串所需的最少操作次数。 

尽管此处未明确显示，但对长度的约束是典型的 Codeforces 规模，因此我们应该假设最大约为 2⋅10^5。 这立即排除了每次测试的三次甚至二次解。 任何解决方案都必须在线性或近线性时间内运行，因为 10^5 次操作已经是每个状态具有恒定工作量的单通道 DP 的实际上限。 

当所有字符都不同时，就会出现微妙的边缘情况。 例如，对于`"abc"`，每个字符都必须独立删除，所以答案是 3。另一种边缘情况是所有字符都相同，例如`"aaaa"`，其中整个字符串可以在单个结构中处理，给出答案 1。 没有计划地从左到右删除的天真贪婪很容易在像这样的模式上失败`"ababa"`，其中配对选择影响未来的结构。 

## 方法

 强力解释将尝试所有可能的方法将字符串划分为可删除的段。 对于每个段，我们会模拟在最优扩展后端点必须匹配的规则下是否可以将其删除。 这很快就会变成指数级的，因为每个切割位置都会导致分支选择，并且验证所有分区将涉及检查每个配置的 O(n) 段。 即使对于 n = 30，这也已经不可行，而在 n = 2⋅10^5 时更是不可能。 

关键的简化来自翻转视角。 我们不考虑任意段删除，而是考虑构建字符串的前缀并确定完全删除它所需的最少操作数。 令 dp[i] 表示删除以位置 i 结尾的前缀所需的最少操作。 

当我们从 i−1 扩展到 i 时，最简单的选择是将字符 s[i] 视为开始新操作，因此 dp[i] = dp[i−1] + 1。 

当 s[i] 可以“匹配”先前的位置 j（其中 s[j] = s[i]）时，就会发生重大改进。 如果我们选择将 i 与 j 连接，那么 j 和 i 之间的所有内容都可以作为同一操作结构的一部分被删除。 这导致了一个转换 dp[i] = dp[j−1] + 1，这意味着我们完成了 j−1 之前的所有内容，然后一个操作覆盖了最终删除以 i 结尾的部分的段。 

挑战在于检查每个 i 的所有 j 的时间复杂度为 O(n^2)。 该结构变得高效，因为我们只关心字符：对于每个字符 c，我们可以在 s[j] = c 的所有位置 j 上保持 dp[j−1] + 1 的最佳值。 那么每次 dp[i] 更新就变成常数时间。 

这将问题简化为一次从左到右扫描并存储 26 个最佳值。

 | --- | --- | --- | --- |
 | 暴力破解分区 | 指数| O(n) | 太慢了 |
 | DP 与角色优化 | O(n) | O(26) | 已接受 |

 ## 算法演练

 我们从左到右处理字符串，同时维护一个动态编程数组和一个按字符索引的小辅助结构。 

1. 初始化 dp[0] = 0，为了方便起见，将 dp 视为字符串的 1 索引。 我们还维护一个数组 best[26]，其中 best[c] 存储字符 c 出现的所有位置 j 中 dp[j−1] + 1 的最小值。 
2.对于每个位置i，首先考虑在i处开始一个新的操作。 这给出 dp[i] = dp[i−1] + 1。这对应于不将 s[i] 与任何较早的字符配对。 
3. 令c = s[i]。 我们现在通过 best[c] 隐式地考虑字符 c 的所有先前出现的 j。 如果我们将 i 连接到某个这样的 j，则成本变为 best[c]，因此我们更新 dp[i] = min(dp[i], best[c])。 
4. 最终确定 dp[i] 后，我们更新当前角色的最佳值。 值 dp[i−1] + 1 表示在位置 i 处开始一个新段，因此我们将其合并到 best[c] 中作为未来匹配的候选。 
5. 继续这个过程，直到字符串末尾，并输出 dp[n]。 

关键思想是 best[c] 充当以先前出现的字符 c 结束的所有可能转换的压缩摘要。 

### 为什么它有效

 在每个位置 i，dp[i] 都会考虑最后一个操作的两种详尽的结构情况：要么从 i 开始，要么在 i 结束，并与某个较早出现的相同字符配对。 任何最佳解决方案都必须属于这些类别之一，因为最终操作必须在 i 处具有右边界，并且其左边界必须是具有匹配字符的某个 j 。 最佳数组保证在所有此类 j 中，我们始终保留最佳 dp[j−1] + 1 值，因此不会丢失候选转换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    if n == 0:
        print(0)
        return

    dp = [0] * (n + 1)
    INF = 10**18
    best = [INF] * 26

    for i in range(1, n + 1):
        c = ord(s[i - 1]) - ord('a')

        dp[i] = dp[i - 1] + 1

        dp[i] = min(dp[i], best[c])

        candidate = dp[i - 1] + 1
        if candidate < best[c]:
            best[c] = candidate

    print(dp[n])

if __name__ == "__main__":
    solve()
```该代码直接实现了前面描述的DP。 dp 数组跟踪每个前缀的最佳答案。 最好的数组根据字符标识压缩所有转换，因此我们永远不会显式迭代以前的出现。 

一个微妙的点是更新的顺序：best[c] 在计算 dp[i] 之后更新，确保我们不会使用位置 i 作为其自己的前任。 候选 dp[i−1] + 1 恰好对应于在 i 处开始新操作的成本，这与同一角色的未来位置相关。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    s = input().strip()
    n = len(s)
    dp = [0] * (n + 1)
    INF = 10**18
    best = [INF] * 26

    for i in range(1, n + 1):
        c = ord(s[i - 1]) - ord('a')
        dp[i] = dp[i - 1] + 1
        dp[i] = min(dp[i], best[c])
        best[c] = min(best[c], dp[i - 1] + 1)

    return str(dp[n])

 ## 边缘情况

 像这样的单字符字符串`"a"`是 dp[1] = 1 的基本情况，因为我们必须执行至少一个操作。 该算法直接处理这个问题，因为 dp[1] 被初始化为 dp[0] + 1，并且 best 会在之后更新而不会受到干扰。 

完全统一的字符串，例如`"aaaaa"`展示了最大程度的重复利用。 从 i = 2 开始，best['a'] 始终包含 dp[i−1] + 1 = 1，因此每个 dp[i] 都会折叠为 1。跟踪证实，一旦看到一个字符，所有未来出现的字符都可以附加到相同的最佳结构。 

严格交替的字符串，例如`"ababab"`练习在角色之间反复切换。 每个字符交替都会阻止不同字母之间的远程重用，因此与统一字符串相比，dp 增长缓慢。 该算法可以正确处理此问题，因为 best 是按字符索引的，因此“a”和“b”之间不会发生交叉污染。
