 ## 问题理解

 该任务是从一个非常小的固定集合中选择不小于给定整数的最小数字。 “好数字”是已知的，并且仅限于六个特定值：6、9、66、69、96 和 99。对于每个输入整数，目标是扫描该集合并选择至少与输入一样大的最小元素。 

输入只是表示查询的一个值或一系列值。 每个查询都会问同样的问题：在这些预定义的候选者中，哪一个是第一个不低于给定阈值的。 输出是每个查询选择的候选者。 

就计算量而言，约束非常小，因为候选集永远不会改变并且大小恒定。 即使有很多查询，每个查询也最多需要六次比较。 这使得解决方案在查询数量的微不足道的线性时间内得到了很好的解决方案。 

主要的微妙之处来自边界行为。 如果输入恰好等于其中一个好的数字，则答案必须是该数字本身，而不是下一个更大的数字。 例如，输入 66 应返回 66，而输入 67 应跳转到 69。仅检查严格更大值的粗心实现将在精确匹配上失败。 另一个边缘情况是输入大于 99，其中正确的行为取决于问题预期。 在此版本中，由于 99 是最大的好数，因此，如果问题保证此类输入有效，则任何大于 99 的输入通常仍会映射到 99，否则未定义。 这个简单版本的标准解释是输入在存在有效答案的范围内。 

## 方法

 蛮力的想法是直接枚举。 对于每个查询，我们迭代所有六个候选数字并跟踪满足条件“候选大于或等于 n”的最小值。 这是有效的，因为正确性不依赖于比较值之外的排序假设。 

这种方法在精神上已经是最佳的，因为数据集是固定的并且很小。 每个查询的最坏情况成本是六次比较，因此即使对于大量查询，总工作量也与查询数量保持线性关系，并且常数因子非常小。 

使问题变得微不足道的关键观察是搜索空间不是动态的。 除了可选地存储列表之外，不需要对大域进行排序、二分搜索或预处理。 该结构本质上是对恒定大小数组的静态查找。 

稍微“工程化”的版本对列表进行预排序，并从最小的元素向上扫描一次。 这保证了一旦找到有效的候选人就可以尽早停止。 但由于只有六个值，即使是最简单的扫描实际上也是恒定时间。

 ## 算法演练

 我们使用固定的好数字列表独立地解决每个查询。 

1. 将六个好数字存储在列表中：[6, 9, 66, 69, 96, 99]。 这种表示允许简单迭代而无需任何计算。 
2. 对于每个输入值n，用大于任何可能候选值的值初始化变量answer，或者不设置它并通过比较计算它。 
3. 迭代固定列表中的每个数字 x。 
4. 如果 x 大于或等于 n，则将 x 视为潜在答案。 跟踪迄今为止遇到的此类 x 的最小值。 
5. 检查完所有候选后，输出存储的最小有效值。

步骤 4 使用最小操作而不是提前停止的原因是，不能保证列表在所有实现中都已排序。 如果我们事先对其进行排序，我们可以在第一个匹配时立即返回，但这是一个实现选择而不是要求。 

### 为什么它有效

 正确性依赖于候选集是完整且有限的这一事实。 每个有效答案都必须属于这个集合，并且它们之间没有可能改变结果的隐藏数字。 因为我们检查所有可能性并选择满足约束的最小可能性，所以我们不会错过更好的有效答案，也不会选择无效的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return

    nice = [6, 9, 66, 69, 96, 99]
    out = []

    for s in data:
        n = int(s)
        best = None
        for x in nice:
            if x >= n:
                if best is None or x < best:
                    best = x
        out.append(str(best))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案一次读取所有输入令牌，以安全地处理单行和多行格式。 每个标记都被视为一个独立的查询。 对于每个查询，它都会扫描六个数字的固定列表，并在找到有效数字时更新最佳候选数字。 

关键的实现细节是处理初始状态`best`。 使用`None`避免与哨兵值的意外比较，并确保当第一个有效候选者出现在列表中较晚时的正确性。 

## 工作示例

 考虑输入序列`7`和`66`。 

为了`n = 7`，我们评估每个候选人。

 | --- | --- | --- |

 | 9 | 是的 | 9 |
 | 66 | 66 是的 | 9 |
 | 69 | 69 是的 | 9 |
 | 96 | 96 是的 | 9 |

 最终答案是9，因为它是不小于7的最小候选者。 

对于`n = 66`，其进展为：

 | 候选人| 检查 x ≥ n | 当前最佳|

 | 6 | 没有| 无 |

 | 96 | 96 是的 | 66 | 66
 | 99 | 99 是的 | 66 | 66

 输出为 66，显示了边界处相等性的正确处理。 

这些痕迹确认平等被正确对待，并且算法始终选择最小的合格候选者而不是第一个匹配的候选者。

 ## 边缘情况

 当输入小于最小的好数时，算法总是返回 6，因为它是第一个满足条件的候选者。 这是有效的，因为每个候选者都会被明确检查，并且保证包含 6 个候选者。 

当输入等于边界值之一（例如 6、9 或 99）时，相等性检查`x >= n`确保候选者本身被选择而不是向前跳。 例如，输入 9，扫描遇到 9 并立即将其视为有效，防止意外选择 66。 

当输入超过 99 时，行为取决于问题约束中是否存在此类输入。 如果是，则算法不会返回有效的候选者，除非明确处理。 在这个简单版本的大多数解释中，输入受到限制，因此有效答案始终存在于集合中，这意味着这种情况在实践中不会发生。
