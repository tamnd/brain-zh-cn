 ## 解决方案
 ## 问题理解

 我们有一个网格，其中的移动仅限于两个方向：向右和向下。 有些细胞含有障碍物，通常踏入障碍物会阻碍运动。 不同的是，我们可以突破障碍，但仅限于方向限制，方向限制取决于我们如何到达当前单元格。 

在每一步中，我们不仅关心当前单元格，还关心我们进入它的方向。 从一个单元格开始，我们可以向右或向下移动。 如果我们尝试进入一个障碍单元，我们是否可以通过它取决于我们进入当前单元的方向是否与我们离开它的方向相匹配。 

这将问题从标准网格最短路径或可达性问题转变为状态必须对位置和到达方向进行编码的问题。 目标是确定我们是否可以根据这些规则从网格起点行驶到目的地。 

输入表示矩形网格，通常包含阻塞和空闲单元。 输出是一个二进制答案，指示是否存在有效路径。 

这些约束与在网格上以线性时间运行的解决方案一致。 网格大小总计约二十万个单元表明预计会进行 O(nm) 动态编程或 BFS 式遍历。 任何试图显式探索路径的方法都会很快爆炸，因为每个单元都可以用不同的传入方向重新访问，从而有效地将状态空间加倍。 

忽略方向的天真的方法会完全失败，因为它将障碍物穿越视为静态。 例如，假设我们有一个配置，仅当从左侧到达时才允许移动到被阻止的单元格中，而从上方到达时则不允许。 标准的 BFS 要么会过多计算可达状态，要么会错误地拒绝有效状态。 

当唯一有效路径需要从路径早期的非常特定方向进入单元格时，会出现另一个微妙的边缘情况。 如果我们不跟踪方向作为状态的一部分，我们可能会将单元格标记为访问过早，并修剪唯一有效的延续。 

## 方法

 强力解决方案会将每个状态视为由位置和用于到达该状态的方向组成的对。 从每个状态，我们尝试过渡到右和下邻居，检查突破障碍规则是否允许移动。 这可以通过扩展状态图实现为 BFS 或 DFS。 

正确性很简单，因为每条合法的运动规则都是直接执行的。 然而，状态的数量就成了问题。 每个单元最多可以通过两种方式到达，并且从每一种方式我们都可以向两个方向分支。 在最坏的情况下，这会创建一个网格单元数量约为四倍的状态图，并且每次状态转换都是 O(1)，但如果不仔细控制，我们仍然有多次重新访问状态的风险。 

关键的观察是，我们存储的方向可以简化为只有两种可能性：来自左侧或来自上方。 一旦我们将其编码为动态编程表或距离数组的一部分，转换就变得确定性，并且每个状态最多被处理一次。 这将问题转化为分层网格图上的最短路径或可达性计算。 

因为所有转换的成本相同，所以 BFS 就足够了。 如果我们将突破障碍解释为可能允许或不允许遍历的条件，那么每个状态的工作量仍然保持在 O(1) 以内，因此标准的 0-1 BFS 甚至带有队列的简单 BFS 就足够了。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 无需剪枝的蛮力状态 BFS | O(nm) 最差，重新访问后可能会更高 | O(纳米) | 风险/低效|
 | 方向感知 BFS / DP | O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 根据我们到达的方式，我们用两种可能的状态对每个网格位置进行建模：从左侧或从上方。 对于每个单元，我们维护它在这两种状态中是否可达。 

1. 使用起始单元初始化队列。 我们认为它可以通过两个可能的传入方向到达，因为第一次移动没有先验约束。 这避免了人为限制初始扩展。 
2. 当队列不为空时，提取由当前单元格和进入该单元格的方向组成的状态。 这个状态完全决定了未来的移动规则是否可以应用。 
3. 从当前单元格开始，尝试向右移动。 如果目标单元格在边界内，我们检查它是否被阻挡。 如果是免费的，我们可以随时搬家。 如果被阻止了，只有规则允许打破它，我们才能移动，这取决于传入方向是否与移动方向匹配。 如果移动有效并且目标状态尚未被访问，我们将其入队。 
4. 重复相同的逻辑向下移动。 同样的约束适用：阻塞的单元格需要方向一致性条件成立。 
5. 如果我们在任何有效状态下到达右下角的单元格，我们就成功终止。 否则，在穷尽所有可达状态后，目的地将无法到达。 

其中心思想是，每个状态都编码足够多的历史来确定下一步的合法性，不需要更多。 

这样做的原因是问题的约束仅取决于上一个移动方向和下一个移动方向，而不取决于完整的路径历史。 这使得该过程成为马尔可夫式的：一旦我们确定了当前的单元格和进入方向，所有未来的决策都独立于之前的步骤。 因此，折叠到达相同状态的所有路径是安全的，并且通过将状态标记为已访问，我们永远不会失去最佳或有效的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    
    # visited[x][y][dir]
    # dir: 0 = came from up, 1 = came from left
    visited = [[[False, False] for _ in range(m)] for _ in range(n)]
    
    q = deque()
    
    # start state: we allow both initial directions
    visited[0][0][0] = visited[0][0][1] = True
    q.append((0, 0, 0))
    q.append((0, 0, 1))
    
    while q:
        x, y, d = q.popleft()
        
        for ndx, ndy, nd in [(0, 1, 1), (1, 0, 0)]:
            nx, ny = x + ndx, y + ndy
            if nx >= n or ny >= m:
                continue
            
            cell_blocked = (grid[nx][ny] == '#')
            
            if cell_blocked:
                # can only break if direction matches
                if d != nd:
                    continue
            
            if not visited[nx][ny][nd]:
                visited[nx][ny][nd] = True
                q.append((nx, ny, nd))
    
    if visited[n-1][m-1][0] or visited[n-1][m-1][1]:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```该实现显式地跟踪方向状态作为访问数组的第三个维度。 每个转换都会对我们是向右还是向下移动进行编码，并使用它来确定是否允许我们打破阻塞的单元格。 队列确保 BFS 式探索，因此每个状态都会处理一次。 

一个微妙的点是初始化。 我们在 (0, 0) 处播种两个方向状态，因为第一次移动没有前驱方向，并且限制它会错误地消除依赖于初始方向的有效路径。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(纳米) | 每个单元方向状态最多被访问一次，并且每次转换的时间复杂度为 O(1) |
 | 空间| O(纳米) | 我们存储每个单元和两个方向的访问状态 |

 网格的处理时间相对于其大小呈线性，这适用于 nm 可达数十万的约束。 内存使用量也是线性的，并且完全符合典型限制。

 ## 边缘情况

 一个关键的边缘情况是单细胞网格。 该算法在起始单元处初始化两个方向状态，因此 (0,0) 可以立即到达并正确返回 YES。 

另一种边缘情况涉及网格，其中只能通过强制方向一致性链进行移动。 在这种情况下，没有方向跟踪的幼稚 BFS 会错误地合并状态，并高估或低估可达性。 这里的状态扩展通过区分每个单元格的进入方式来防止这种情况发生。 

最后一个微妙的情况是，同一单元需要两个方向来继续不同的分支。 因为我们独立存储两个方向状态，所以允许在不同的进入方向下重新访问相同的坐标，从而保持分支结构的正确性。
