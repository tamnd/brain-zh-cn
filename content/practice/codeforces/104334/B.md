 ## 解决方案
 ## 问题理解

 我们得到一个简单的多边形，由其顶点按逆时针顺序描述。 多边形不一定是凸多边形。 任务是确定重复应用几何“修复”操作后获得的最终多边形，该操作以非常特定的方式修改凹面区域，直到形状变成凸面。 

该操作具有几何解释：它选择严格位于当前非凸结构内部的最大边界点链，端点位于凸包上，然后跨其端点的中点反映该链。 这不会改变最终稳定配置中的点集； 它只是逐渐“拉直”凹部。 

一个关键的观察结果是，尽管看似动态的过程，但最终形状是由初始多边形唯一确定的，并且不依赖于每个步骤应用的有效操作。 输出正是这个最终的凸多边形，以逆时针顺序的整数坐标顶点序列给出，从字典顺序最小的顶点开始。 

约束允许最多 100,000 个顶点，因此任何比线性算法更糟糕的解决方案都会陷入困境。 所描述的操作的三次甚至二次几何模拟是完全不可行的，因为每个操作都会影响长边界段，并且可能存在线性数量的此类操作。 

最危险的边缘情况来自于了解转换实际上保留了什么。 幼稚的解释可能会尝试直接模拟反射操作，但这会导致对中间几何形状的错误假设。 

一个微妙的陷阱是假设局部凸化或单调链修复（如局部应用的标准凸包技巧）就足够了。 例如，形状像“之字形”走廊的多边形可能需要全局校正而不是局部修复，并且天真的迭代外壳更新将无法捕获重复段反射所暗示的对称性。 

## 方法

 蛮力的想法是完全按照所描述的方式模拟该过程。 我们反复找到一个以两个外壳顶点为界的凹区域，反映内部链，并更新多边形。 每个此类操作都可能需要线性时间来识别船体，并需要另一个线性时间来更新受影响的段。 由于在最坏情况下可能存在 O(N) 此类操作，其中每个步骤仅删除少量凹性，因此总复杂度变为 O(N^2) 或更糟。 当N达到100,000时，这远远超出了可接受的范围。 

关键的见解是，该操作并不是真正的“局部平滑”，而是非常具体的线性变换下的全局凸化：反映穿过中点的边界段保留了中点结构，并有效地用镜像凸链替换了凹链。 这意味着最终形状仅取决于凸包几何形状以及边界点在包边缘上的配对方式。 

如果我们从不同的角度来看这个过程，每个非外壳边缘最终都会“翻转”到与凸包边界对齐。 重复的中点反射增强了对称性，消除了所有凹面，这意味着最终的多边形正是原始点集的凸包，但有一个关键的转折：包的顶点在保留整数坐标的累积反射下进行变换。 

这导致标准凸包计算，然后重建与诱导变换一致的最终边界。 重要的结构结果是边界上没有内点存在，最终的多边形正是原始顶点的凸包。

因此，问题简化为计算一组点的凸包，然后从字典顺序最小的顶点开始按逆时针顺序输出。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(N²) 或更差 | O(N) | 太慢了|
 | 凸包（单调链）| O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 我们使用单调链结构计算给定多边形顶点的凸包。 

1. 从输入中读取所有点并将它们存储为坐标对。 这为我们提供了初始多边形的完整顶点集。 
2. 按 x 坐标对点进行排序，按 y 坐标打破平局。 这种顺序使我们能够有效地构建上下船体。 
3. 通过从左到右迭代来构建下部船体。 对于每个新点，我们认为船体中的最后两个点和当前点始终形成逆时针旋转。 如果没有，我们删除中间点。 这确保了我们继续时边界保持凸形。 
4. 使用相同的规则从右向左迭代来构建上层船体。 这捕获了下部船体不包括的剩余边界。 
5. 连接下壳和上壳，删除重复的端点。 这将按逆时针顺序生成完整的凸多边形。 
6. 根据输出规范的要求，旋转结果列表，使字典顺序最小的顶点排在最前面。 

正确性来自于这样的事实：原始多边形中的任何凹顶点在重复的中点反射操作下都不能保留在最终边界上，因为它总是严格位于凸包的支撑线内。 唯一幸存的顶点是位于凸包边界上的顶点，单调链算法精确计算这些点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def cross(o, a, b):
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

def convex_hull(points):
    points = sorted(set(points))
    if len(points) <= 1:
        return points

    lower = []
    for p in points:
        while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
            lower.pop()
        lower.append(p)

    upper = []
    for p in reversed(points):
        while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)

    return lower[:-1] + upper[:-1]

def rotate_to_lexmin(poly):
    idx = 0
    for i in range(1, len(poly)):
        if poly[i] < poly[idx]:
            idx = i
    return poly[idx:] + poly[:idx]

def main():
    data = list(map(int, sys.stdin.read().strip().split()))
    n = data[0]
    pts = []
    idx = 1
    for _ in range(n):
        x = data[idx]
        y = data[idx + n]
        idx += 1
        pts.append((x, y))

    hull = convex_hull(pts)
    hull = rotate_to_lexmin(hull)

    print(len(hull))
    for x, y in hull:
        print(x, y)

if __name__ == "__main__":
    main()
```该解决方案首先读取点并形成标准点集。 凸包函数是一种经典的单调链实现，它使用叉积测试强制执行严格的凸性。 删除产生非左转的点，确保只有边界顶点幸存。 

最后一步旋转外壳，使最小的字典顶点位于第一个，以满足输出要求。 

一个微妙的实现细节是交叉产品条件的严格性。 使用`<= 0`确保删除共线边界点，这是必需的，因为输出禁止连续的共线三元组。 

另一个重要的细节是重复数据删除`set(points)`，这是安全的，因为相同的坐标会破坏船体的正确性。

 ## 边缘情况

 关键的边缘情况是所有点共线。 在这种情况下，每个点都位于一条线段上，并且凸包退化为两个极端端点。 该算法正确地处理了这个问题，因为叉积到处都变为零，并且单调链由于以下原因删除了中间点：`<= 0`健康）状况。 

另一种情况是多边形已经是凸的。 船体构造不删除除共线顶点之外的任何顶点，保留了原始的凸边界结构。 

最后一个微妙的情况是重复坐标。 基于集合的重复数据删除可确保重复项不会破坏排序或交叉产品决策，从而防止错误的外壳循环或零区域分段。
