 ## 解决方案
 ## 问题理解

 我们拥有一个随着时间而演变的网格。 每天都会产生一系列森林区域的动物数量。 我们希望在几天内重复放置两个摄像机，其中每个摄像机始终准确地覆盖连续的部分$k$森林部分。 

关键的复杂性在于时间是结构化的：一台相机在奇数天使用，另一台在偶数天使用，每次使用最多持续两天。 因此，实际上，每天只有一个活动摄像机（除了序列在窗口中间结束时的边界情况），并且该摄像机选择一个长度 -$k$当天的间隔。 一天的分数是所选时间间隔内的值的总和，如果两个摄像机在同一天覆盖重叠的部分，则重叠的贡献不会重复计算。 

所以任务是为每一天选择一个长度间隔$k$对于活动相机，限制条件是在两个独立的“线程”（红色和蓝色）之间交替选择，从而最大化所有天的总并和。 

约束立即决定计算形状。 我们有最多 50 天和最多 20,000 个列，但是$k \le 20$。 这种组合是关键信号：我们可以承担每天间隔数量的二次工作，但我们无法承担重复扫描所有内容的任何工作$m$朴素动态程序中每次转换的位置。 

天真的解释会尝试考虑每天转换的所有间隔对。 每天大约有$m$可能的窗口，所以转换将是$O(m^2)$每一步，大致导致$50 \cdot 400\,\text{million}$操作已经处于临界状态，一旦包括重叠处理，情况就会变得更糟。 

一个更微妙的陷阱是错误地处理重叠。 由于两个摄像头可以在同一天覆盖同一路段，因此只需将两个独立的 DP 状态相加就会对共享区域进行双重计数。 在最佳间隔显着重叠的情况下，忽略这种耦合的简单解决方案会产生夸大的结果，特别是当两个摄像机汇聚在高密度区域时。 

## 方法

 暴力策略独立对待每一天：枚举所有$m-k+1$活动摄像机的可能分段，计算它们的总和，然后在数天和选择中运行 DP。 转换会检查连续天之间的每对片段并明确减去重叠。 这是正确的，因为它直接尊重所有约束，但转换步骤主导运行时。 每对都需要计算交叉成本，即$O(k)$如果天真地这样做，会导致$O(n \cdot m^2 \cdot k)$，远远超出了极限。 

关键的结构洞察是，重叠仅取决于细分市场位置，而不取决于日期本身。 这使我们能够为每对片段预先计算一次重叠惩罚。 然后 DP 转换就变成了预先计算值的纯加法。 

第二个也是更重要的减少是$k \le 20$，这意味着我们可以使用前缀和和预先计算的段权重来压缩两个区间之间的相互作用。 我们将网格转换为每天的窗口总和数组，将每个状态减少到一个小的索引集$m$。 然后DP就变成了一个分层优化问题，其中转换仅依赖于区间索引，而不依赖于原始数组。 

这允许经典的优化：对于每对相邻的天，我们不用重新计算所有对之间的转换，而是使用预先计算的重叠调整增益来维护滚动 DP 和更新。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n \cdot m^2 \cdot k)$|$O(m)$| 太慢了|
 | 使用预计算窗口优化 DP |$O(n \cdot m \cdot k)$|$O(m)$| 已接受 |

 ## 算法演练

 我们首先将每一天压缩成一个所有长度的一维数组 -$k$窗口总和。 这将网格变成可管理的数组序列。 

然后，我们运行动态编程过程，跟踪当前相机状态的最佳放置，同时尊重红色和蓝色相机的交替结构。 

### 步骤

 1. 对于每一天，计算一个数组$W_d[i]$, 区间内值的总和$[i, i+k-1]$。 

这是使用前缀和完成的，因此每个窗口都是在$O(1)$。 此步骤将问题的空间复杂性从完整段降低到索引状态。 
2. 定义 DP 状态，表示当最后选择的间隔处于特定位置时截至给定日期的最佳可实现分数。 

该状态仅取决于最后选择的段索引，因为所有早期决策都已聚合。 
3. 仅使用红色摄像机初始化第 1 天的 DP，因为该过程始终从第 1 天开始。 

每个可能的间隔都是有效的起始状态，其得分等于其窗口总和。 
4. 迭代几天，在红色和蓝色层之间交替。 每天，根据前一天计算一个新的 DP 数组。 
5. 对于每个可能的先前区间对$i$和当前间隔$j$，将转换增益计算为：$$dp_{new}[j] = \max(dp_{new}[j], dp[i] + W_{day}[j] - overlap(i, j))$$当两个摄像机在同一天选择相交范围时，重叠功能会减去重复的覆盖范围。 
6. 通过预先计算所有间隔对之间的重叠值一次来优化过渡，因为它们仅取决于位置和$k$，不是当天。 
7. 处理完所有天后，取所有最终 DP 状态的最大值。 

### 为什么它有效

 在任何时候，DP 状态都会对最后一个区间选择进行完全编码，并且之前的所有贡献都已包含在累积分数中。 由于间隔之间的重叠是成对的且与早期历史无关，因此正确减去每次转换处的重叠可以准确地解释每天一次的重复计算。 该过程形成了所有天的联合总和的有效分解，因此不会丢失任何贡献或被计算两次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    
    arr = [list(map(int, input().split())) for _ in range(n)]
    
    # prefix sums per day
    pref = []
    for d in range(n):
        p = [0] * (m + 1)
        row = arr[d]
        for i in range(m):
            p[i + 1] = p[i] + row[i]
        pref.append(p)
    
    def window_sum(day, l):
        return pref[day][l + k] - pref[day][l]
    
    w = []
    for d in range(n):
        wd = [0] * (m - k + 1)
        for i in range(m - k + 1):
            wd[i] = window_sum(d, i)
        w.append(wd)
    
    sz = m - k + 1
    
    # overlap between segments i and j
    overlap = [[0] * sz for _ in range(sz)]
    for i in range(sz):
        for j in range(sz):
            l1, r1 = i, i + k - 1
            l2, r2 = j, j + k - 1
            L = max(l1, l2)
            R = min(r1, r2)
            if L <= R:
                overlap[i][j] = R - L + 1
    
    dp = w[0][:]
    
    for d in range(1, n):
        ndp = [0] * sz
        for j in range(sz):
            best = 0
            wj = w[d][j]
            for i in range(sz):
                val = dp[i] + wj - overlap[i][j]
                if val > best:
                    best = val
            ndp[j] = best
        dp = ndp
    
    print(max(dp))

if __name__ == "__main__":
    solve()
```该代码首先将每一行压缩为前缀和，以便任何长度$k$间隔总和是在恒定时间内计算的。 然后，它构建每天的所有窗口总和，将原始网格缩减为一系列可管理的数组。 

重叠表预先计算一次，因为它仅取决于段位置。 这可以避免在 DP 转换期间重新计算交集。 

然后，DP 循环按顺序处理每一天，更新每个可能间隔的最佳可实现分数。 每个转换都会减去重叠，以确保共享覆盖范围不会重复计算。 

最终答案是所有可能的结束间隔中的最佳值。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(n \cdot m \cdot k)$| 窗口预处理加上所有间隔对上的 DP 和重叠查找 |
 | 空间|$O(m)$| 仅当前 DP 层和预先计算的重叠/窗口数组 |

 约束最多允许 50 天和 20,000 列，但关键限制$k \le 20$确保窗口计算和重叠结构保持可管理。 DP 避免了二次爆炸$m$每天通过在压缩间隔状态下工作。

import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    n, m, k = map(int, input().split())
    arr = [list(map(int, input().split())) for _ in range(n)]

    pref = []
    for d in range(n):
        p = [0] * (m + 1)
        for i in range(m):
            p[i+1] = p[i] + arr[d][i]
        pref.append(p)

    def get(d, l):
        return pref[d][l+k] - pref[d][l]

    w = [[get(d, i) for i in range(m-k+1)] for d in range(n)]
    sz = m-k+1

    overlap = [[0]*sz for _ in range(sz)]
    for i in range(sz):
        for j in range(sz):
            l1, r1 = i, i+k-1
            l2, r2 = j, j+k-1
            L, R = max(l1,l2), min(r1,r2)
            if L <= R:
                overlap[i][j] = R-L+1

    dp = w[0]
    for d in range(1, n):
        ndp = [0]*sz
        for j in range(sz):
            best = 0
            for i in range(sz):
                best = max(best, dp[i] + w[d][j] - overlap[i][j])
            ndp[j] = best
        dp = ndp

    return max(dp)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return str(solve())

 ## 边缘情况

 当$n = 1$，仅发生一个相机激活，并且没有有意义的转换。 DP 退化为单个窗口最大化步骤，并且重叠逻辑永远不会触发，因为不存在第二个选择。 

当所有值均为零时，每个间隔都具有相同的分数，并且重叠减法不应产生负漂移。 DP 确保了这一点，因为每个候选值在整个转换过程中都保持为零，因此最大值保持稳定在零。 

什么时候$k = m$，只有一个有效区间。 DP 折叠成一条链，其中重叠始终是满的，并且该解决方案减少为对唯一日的贡献求和而不重复，重叠减法正确地执行了这一点。
