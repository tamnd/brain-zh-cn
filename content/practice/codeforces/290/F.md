 ## 解决方案
 ## 问题理解

 给定一个最多有 20 个顶点和最多 400 个边的无向图，我们需要确定是否存在一条简单路径可以访问每个顶点一次。 这就是哈密顿路径问题的决策形式：我们不被要求构建路径，只需要说明连续顶点通过边连接的情况下是否存在至少一种这样的顶点排序。 

关键细节是图表的比例。 对于最多 20 个顶点，指数方法变得可行，但任何像直接枚举顶点的所有排列之类的方法都已经是边界了，因为$20!$太大了。 然而，任何对顶点子集进行状态压缩的解决方案，其数量级为$2^n \cdot n^2$，是完全可行的。 

一个微妙的一点是，该图可能包含自环或多边，而这些并不影响哈密顿路径的存在。 自循环对于必须在不同顶点之间移动的路径毫无帮助，并且重复的边对于连接来说是多余的。 

经常出现的一个天真的错误是将其解释为连接问题。 例如，检查图是否连通并且所有顶点的度数至少为 1 是远远不够的。 像具有 20 个顶点的星形这样的连通图，有一个连接到所有叶子的中心，但没有哈密顿路径，因为进入中心的任何路径只能离开它一次，因此不可能访问单个链中的所有叶子。 

另一个失败案例来自于贪婪遍历。 即使存在有效的哈密顿路径，从随机节点开始并始终前往未访问过的邻居也可能会过早陷入困境。 局部选择不编码全局约束。 

## 方法

 暴力方法将尝试顶点的所有排列并检查连续的顶点是否由边连接。 对于每个排列，我们验证邻接性$O(n)$，并且有$n!$排列，给出总体复杂度$O(n! \cdot n)$。 即使在$n = 20$，这是完全不可行的。 

一旦我们发现我们只关心已访问的顶点子集以及路径中的最后一个顶点，问题的结构就会发生显着变化。 访问同一组顶点并在同一顶点结束的两种不同排列在未来的可扩展性方面是等效的。 这表明了子集上的动态规划公式。 

我们定义一个状态来捕获已访问顶点的子集和路径的端点。 从任何状态，我们都尝试将路径延伸到未访问过的邻居。 这减少了从排列到子集转换的搜索空间，将棘手的枚举变成易于管理的$2^n \cdot n$状态空间。 

这是标准的哈密顿路径 DP，在这里它完全适合，因为$n \le 20$， 制作$2^n \approx 10^6$，它足够小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（排列）|$O(n! \cdot n)$|$O(n)$| 太慢了 |
 | 路径上的位掩码 DP |$O(n^2 \cdot 2^n)$|$O(n \cdot 2^n)$| 已接受 |

 ## 算法演练

 我们构建一个动态规划表，在其中跟踪某个顶点子集是否可以形成终止于特定顶点的有效路径。 

1. 我们使用长度的位掩码来表示每个顶点子集$n$。 位掩码精确编码部分路径中已包含的顶点。 这种表示很自然，因为过渡一次仅添加一个顶点。 
2.我们定义一个DP数组，其中`dp[mask][v]`如果存在一条恰好访问以下顶点的路径，则为真`mask`并在顶点结束`v`。 该状态捕获进一步扩展路径所需的所有信息。 
3. 我们通过设置来初始化DP`dp[1 << v][v] = True`对于每个顶点`v`。 每个顶点单独形成一条长度为一的平凡路径。 
4. 我们从小到大迭代所有掩码。 对于每个掩码，我们尝试所有可能的端点`v`。 如果`dp[mask][v]`是的，我们尝试延长路径。 
5. 延长状态`(mask, v)`，我们尝试所有邻居`to`的`v`。 如果`to`不在`mask`，我们设置`dp[mask | (1 << to)][to] = True`。 此步骤与将新顶点附加到当前路径完全对应。 
6.处理完所有状态后，我们检查是否存在任何顶点`v`这样`dp[(1 << n) - 1][v]`是真的。 如果是这样，则存在哈密顿路径。 

正确性取决于以下事实：每条有效的哈密顿路径都有最后一个顶点，并且 DP 最终将准确构造通向该路径的子集序列。 

### 为什么它有效

 不变的是`dp[mask][v]`当且仅当存在一条恰好访问 中的顶点的简单路径时才为真`mask`并结束于`v`。 每个转换都保持简单性，因为我们只移动到未访问的顶点，并且考虑有效路径的每个可能的扩展。 由于每个哈密顿路径都对应于子集添加的某种顺序，因此它必须出现在该状态空间中，并且不会引入无效状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [[False] * n for _ in range(n)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u][v] = True
        adj[v][u] = True

    if n == 1:
        print("Yes")
        return

    size = 1 << n
    dp = [[False] * n for _ in range(size)]

    for i in range(n):
        dp[1 << i][i] = True

    for mask in range(size):
        for v in range(n):
            if not dp[mask][v]:
                continue
            if mask == (1 << n) - 1:
                continue
            for to in range(n):
                if not adj[v][to]:
                    continue
                if mask & (1 << to):
                    continue
                dp[mask | (1 << to)][to] = True

    full = (1 << n) - 1
    for v in range(n):
        if dp[full][v]:
            print("Yes")
            return

    print("No")

if __name__ == "__main__":
    solve()
```使用邻接矩阵使得边缘检查的时间恒定。 这很重要，因为 DP 已经在所有子集和端点上运行，并且每次转换的任何对数开销都将过于昂贵。 

DP 表首先通过位掩码进行索引，因为子集迭代是自然的外循环。 每个状态仅沿着实际边缘扩展，并且我们显式地跳过到已访问顶点的转换以确保路径有效性。 

最终扫描结束`dp[full]`访问所有顶点后检查是否有任何端点可达。 

## 工作示例

 ### 示例 1

 输入图：```
3 2
1 2
2 3
```我们期望像 1 → 2 → 3 这样的哈密顿路径。 

| 面膜| 端点 v | dp 状态 | 过渡 |
 | --- | --- | --- | --- |
 | 001| 1 | 真实 | 开始 |
 | 010| 2 | 真实 | 开始 |
 | 100 | 100 3 | 真实 | 开始 |
 | 011| 2 | 真实 | 1→2 |
 | 110 | 110 3 | 真实 | 2→3 |
 | 111 | 111 3 | 真实 | 1→2→3 |

 在最后一个掩码中，至少有一个端点是可到达的，因此答案是“是”。 

此跟踪显示部分路径如何随着子集的增长而自然合并。 

### 示例 2

 输入：```
4 2
1 2
3 4
```该图是断开连接的，因此不存在哈密顿路径。 

所有 DP 状态仍局限于其组件内，并且任何转换都不能从 {1,2} 移动到 {3,4}。 因此没有状态到达掩码 1111。 

DP 永远不会产生全掩码状态，这证实了仅靠子集内部的连接是不够的。

 ## 边缘情况

 一种边缘情况是单顶点图。 DP初始化`dp[1<<0][0] = true`，并且由于这已经对应于完整掩码，因此算法立即成功，正确输出“是”。 

另一种情况是具有孤立顶点的图。 例如，如果顶点 5 没有边，则它只能显示为独立路径。 DP 正确地处理了这个问题，因为从 5 开始的状态无法扩展，并且无法到达全掩码状态。 

更微妙的情况是密集图缺少关键边，从而阻碍了完整排序。 即使大多数顶点高度连接，DP 仍然遵循精确的邻接约束，因此它永远不会错误地组合不兼容的部分路径。
