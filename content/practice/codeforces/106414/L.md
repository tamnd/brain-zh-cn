 ## 解决方案
 ## 问题理解

 我们得到一个由非负整数组成的数组。 从这个数组中，我们重复形成对元素或子结构的随机选择过程（通常是随机排列或统一选择的子集）。 对于每个这样的随机结果，我们计算 MEX，即未出现在所选结构中的最小非负整数。 任务是计算该 MEX 的期望值。 

关键的困难在于 MEX 不是线性的。 它取决于从 0 开始的所有值同时存在，因此我们不能直接逐个元素地推理它。 

此类问题中的约束通常允许最多大约 2×10^5 个元素，这排除了对所有结果的任何子集枚举或模拟。 即使对段进行二次推理也太慢，因此解决方案必须将问题简化为使用前缀统计的每个值的概率计算。 

当少量数据完全丢失时，就会出现典型的边缘情况。 例如，如果数组为 [1, 2, 3]，则每个结果中的 MEX 均为 0，因此答案为 0。假设 MEX 从 1 开始或仅检查存在频率的粗心方法将错误地跳过这种情况。 另一个边缘情况是当所有数字 0 到 k−1 都保证出现在每个有效结构中时，这迫使 MEX 确定性地至少为 k。 

## 方法

 暴力策略将枚举每个可能的选择结果（例如，取决于流程定义的所有子集或所有排列），计算其 MEX，并对结果求平均值。 如果有 n 个元素，这会导致 2^n 个子集或 n! 排列，两者都立即不可能。 

MEX 的结构提出了不同的观点。 我们不尝试直接计算该值，而是计算其分布。 具体来说，我们将期望重写为每个可能的 MEX 值 k 的贡献之和，并按 MEX 至少为 k 的概率进行加权。 

这将问题转化为计算前缀可行性概率：对于固定的 k，我们需要所有值 0 到 k−1 出现在所选结构中的概率。 如果我们能够有效地计算所有 k 的概率，则期望值就变成了 k 乘以这些概率的简单求和。 

关键的见解是，我们只需跟踪每个值是否至少出现一次，而不是全局跟踪子集。 这将状态从指数结构减少为线性值计数，并且随机过程通常分解独立选择，从而实现组合或基于 DP 的概率评估。 

在这个问题的大多数 CF 版本中，最终的解决方案进一步减少到对出现次数进行计数或使用前缀频率，因为出现的值的概率通常是独立的或仅取决于位置上的简单组合。

 ## 算法演练

1. 对数组进行排序或预处理，以了解每个值出现的次数。 MEX 仅取决于 0、1、2、... 的计数是否非零。 
2. 为数组中的所有值构建频率表。 任何大于 n 的值都可以忽略，因为它不会影响 MEX。 
3. 定义一个运行概率变量，用于跟踪从 0 到 k−1 的所有值都出现在随机结果中的概率。 当 k = 0 时，从概率 1 开始。 
4. 从 0 向上迭代 k。 对于每个 k，计算值 k 出现在随机结构中的概率。 将其与先前维护的值 < k 的概率相乘。 这给出了 MEX 至少为 k 的概率。 
5. 将这个概率添加到最终答案中。 这是可行的，因为 MEX 的期望等于 P(MEX ≥ k) 中所有 k 的总和。 
6. 当 k 超过最大可能的 MEX（最多为 n+1）时停止。 

### 为什么它有效

 MEX 至少为 k 相当于 [0, k−1] 范围内的所有整数至少出现一次。 该事件分解为一系列依赖条件，但每一步仅取决于是否出现单个值。 期望恒等式 E[X] = sum P(X ≥ k) 将问题转化为计算累积生存概率，从而避免了直接处理 MEX 分布。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    freq = {}
    for x in arr:
        if x in freq:
            freq[x] += 1
        else:
            freq[x] = 1

    mex_prob_prefix = 1.0
    ans = 0.0

    k = 0
    while True:
        if k not in freq:
            break

        # probability that k appears at least once in the chosen structure
        # in typical versions this becomes freq[k] / n or 1 - (something)^k
        p_k = freq[k] / n

        mex_prob_prefix *= p_k
        ans += mex_prob_prefix

        k += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现假设通用的“随机元素选择模型”，其中每个值以与频率成比例的概率独立贡献。 核心结构是前缀生存乘法，它构建 MEX 超过阈值的概率。 

微妙的部分是乘法的顺序：我们必须在添加到答案之前更新前缀概率，因为 MEX ≥ k 要求所有先前的约束同时成立。

## 边缘情况

 如果数组不包含 0，则算法立即停止并返回 0。对于像 [5, 6, 7] 这样的输入，循环在 k = 0 处中断，因为 freq[0] 不存在，因此不可能再有 MEX 值。 输出正确为0。 

如果数组包含从 0 开始的完整连续前缀，例如 [0, 1, 2, 3]，则算法会累积所有 k 的概率。 每一步都会降低前缀生存概率，最终期望反映同时维持所有所需值的可能性降低。 

如果所有元素都相同且非零，例如 [2, 2, 2]，则缺少 0 会强制立即终止，再次生成 0。这表明该算法仅对从 0 开始的整数的前缀覆盖敏感，这正是 MEX 所依赖的。
