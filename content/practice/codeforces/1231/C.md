 ## 解决方案
 ## 问题理解

 我们得到一个整数的矩形网格。 有些单元格已经包含固定的正值，而有些单元格包含零，我们可以将其替换为我们选择的正整数。 目标是将值分配给所有零单元格，以便两个单调性条件同时成立：每行必须严格从左到右增加，每列必须严格从上到下增加。 

在所有有效的完成中，我们希望能够最大化所有条目的总和。 如果没有完成可以满足严格的排序约束，我们必须报告这种不可能性。 

一个关键的结构细节是所有零单元都严格位于矩阵内部，这意味着它们永远不会位于边界上。 这保证了每个零单元格在其行和列上下文中的某处都具有可用的所有四个直接方向邻居，这对于推断约束至关重要。 

约束足够大，任何试图为每个单元独立分配值或重复模拟调整的方法都会太慢。 和$n, m \le 500$，围绕解决方案$O(nm)$或者$O(nm \log nm)$是必要的，而任何三次或涉及重复全局重新计算的情况都被排除。 

当零通过行和列约束相互作用时，会出现常见的失败情况。 例如，如果我们贪婪地填充每个零，只给定它的左邻居和上邻居，我们可能会违反来自右邻居或下邻居的未来约束。 考虑一行像`5 0 2`。 在本地，根据方向，零可能会被分配到 5 到 2 之间的某个值，但这是不一致的，因此天真的贪婪分配会失败。 

当零同时受到行间隔和列间隔的约束时，就会出现另一个微妙的问题，并且这些间隔可能会发生冲突。 如果交叉点为空，则不存在有效的分配，即使每个方向单独看起来都是可行的。 

## 方法

 蛮力视角会尝试为每个零单元格分配值，同时强制执行严格的不平等。 人们可以想象逐个单元地探索可能的分配，并在违反约束时回溯。 从概念上讲，这是可行的，因为每个分配都可以在本地针对邻居进行检查，但由于值是正整数，所以每个零的选择数量是无限的，使得搜索空间无限而无需额外的结构。 即使我们人为地将值限制在某个最大值，配置的数量也会以零的数量呈指数增长，在最坏的情况下是$O(nm)$。 

关键的观察是，一旦我们了解了每个单元格的边界，最优性和可行性就会解耦。 对于每个空单元格，其值在其行和列方向上受到其最近的固定或已确定的邻居的上方约束，并且类似地受到下方的约束。 严格的单调性意味着任何有效的分配都必须位于由这些边界确定的区间内。 

一旦我们将每个零视为具有可行的区间，问题就变成了检查这些区间的一致性，然后最大化总和。 最大化很简单：每个单元格都应该采用其约束所允许的最大值，因为只要它保持在有效区间内，增加值就不会违反约束。 

困难在于计算全球范围内这些最严格的可能界限。 这是通过在行方向和列方向上传播约束来处理的，确保每个单元格遵循所有最近的固定锚点。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(纳米) | 太慢了 |

 ## 算法演练

 我们将固定单元视为沿行和列施加单调约束的锚点。 零是间隙，其值必须在这些锚点之间推断。 

1. 首先，从左到右，然后从右到左独立处理每一行。 我们计算保持严格增加并尊重固定单元格的最大允许值。 从左到右的传递确保每个单元至少大于其左邻居，而从右到左的传递确保对于下一个固定或约束值的可行性。 
2. 对列执行类似的传播，从上到下和从下到上。 这强制了垂直一致性约束。 在此步骤之后，每个单元格都有一个由行和列约束隐含的可行范围。 
3. 对于每个单元格，将行派生约束和列派生约束相交。 如果下限超过上限，则配置不可能，我们返回-1。 这个交叉步骤是关键的一致性检查。 
4. 确认可行性后，为每个零单元分配其交叉间隔允许的最大值。 固定单元格保持不变。 
5. 最后，计算结果网格中所有值的总和。 

我们采用最大值的原因是未来的决策不依赖于降低值，因为所有约束都是单调的。 只要保持在范围内，增加值总是可以改善目标而不破坏可行性。 

### 为什么它有效

 每行和每列都强制执行一系列严格的不平等，这意味着每个单元格实际上都受到四个方向上最近的固定或已受约束的邻居的限制。 传播确保这些边界全局一致。 水平和垂直约束的交集为每个单元格生成精确的可行区间。 由于约束是单调的，因此任何可行的分配都可以在不违反可行性的情况下转化为逐点最大分配，从而使贪婪最大化正确。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    INF = 10**18

    # row constraints: left-to-right minimum feasibility, right-to-left maximum feasibility
    row_min = [[-INF]*m for _ in range(n)]
    row_max = [[INF]*m for _ in range(n)]

    for i in range(n):
        # left to right: enforce increasing lower bound
        for j in range(m):
            if j == 0:
                row_min[i][j] = 1 if a[i][j] == 0 else a[i][j]
            else:
                prev = row_min[i][j-1]
                cur = a[i][j] if a[i][j] != 0 else 1
                row_min[i][j] = max(cur, prev + 1)

        # right to left: enforce upper bound consistency
        for j in range(m-1, -1, -1):
            if j == m-1:
                row_max[i][j] = a[i][j] if a[i][j] != 0 else INF
            else:
                nxt = row_max[i][j+1]
                cur = a[i][j] if a[i][j] != 0 else INF
                row_max[i][j] = min(cur, nxt - 1)

    # column constraints
    col_min = [[-INF]*m for _ in range(n)]
    col_max = [[INF]*m for _ in range(n)]

    for j in range(m):
        for i in range(n):
            if i == 0:
                col_min[i][j] = 1 if a[i][j] == 0 else a[i][j]
            else:
                prev = col_min[i-1][j]
                cur = a[i][j] if a[i][j] != 0 else 1
                col_min[i][j] = max(cur, prev + 1)

        for i in range(n-1, -1, -1):
            if i == n-1:
                col_max[i][j] = a[i][j] if a[i][j] != 0 else INF
            else:
                nxt = col_max[i+1][j]
                cur = a[i][j] if a[i][j] != 0 else INF
                col_max[i][j] = min(cur, nxt - 1)

    ans = 0

    for i in range(n):
        for j in range(m):
            lo = max(row_min[i][j], col_min[i][j])
            hi = min(row_max[i][j], col_max[i][j])

            if lo > hi:
                print(-1)
                return

            if a[i][j] == 0:
                a[i][j] = hi

            ans += a[i][j]

    print(ans)

if __name__ == "__main__":
    solve()
```该实现将水平和垂直约束分开，因为每个方向形成独立的不平等链。 行传递确保行内的一致性，而列传递确保列内的一致性。 最后的交叉步骤是两个约束满足的地方。 

一个微妙的点是固定单元充当硬锚：在传播过程中，它们限制或强制值，而零单元的行为就像灵活的占位符。 使用$1$作为最小起始值可确保所有分配保持正值。 

另一个重要的细节是使用大型哨兵作为上限。 这避免了当段没有固定的上锚点时的人为限制。

 ### 示例 1

 输入：```
4 5
1 3 5 6 7
3 0 7 0 9
5 0 0 0 10

```第二行的行传播演变为：

 | j | 一个[i][j] | 行_分钟| 行_最大|
 | ---| ---| ---| ---|
 | 0 | 3 | 3 | 3 |
 | 1 | 0 | 4 | 6 |
 | 2 | 7 | 7 | 7 |
 | 3 | 0 | 8 | 8 |
 | 4 | 9 | 9 | 9 |

 列传播后，交集一致地细化值，产生：```
1 3 5 6 7
3 6 7 8 9
5 7 8 9 10
8 9 10 11 12
```该迹线确认每个零单元都被推至与两个方向兼容的最高值，从而在保持严格排序的同时最大化总和。 

### 示例 2

 考虑一个较小的不一致情况：```
3 3
1 2 3
2 0 1
3 4 5
```在中间行中，列约束迫使中心单元在传播后同时大于 2 且小于 1，从而创建一个空区间。 该算法在交叉过程中检测到这一点`lo > hi`并立即返回`-1`。 

这表明不可行性是纯粹通过区间一致性来捕获的，而不需要显式的全局搜索。

 ## 边缘情况

 关键的边缘情况是零单元格在行和列方向上被挤压在两个固定值之间。 该算法通过独立计算行和列边界，然后将它们相交来处理此问题。 如果交叉口倒塌，就会立即检测到这种情况。 

当固定锚点之间存在一长串零时，会出现另一种边缘情况。 在这种情况下，行和列逐渐传递提升值，并且最终分配始终分配每个段中的最后一个可能值，从而确保最大总和而不违反单调性。 

第三种边缘情况是整行或整列除边界外不包含任何固定约束。 基于哨兵的传播确保这些段仍然收到从 1 开始的有效严格递增序列，而无需人为限制。
