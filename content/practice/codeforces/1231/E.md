 ## 解决方案
 ## 问题理解

 我们有两个长度相等的字符串。 唯一允许的操作是从当前字符串中选取一个字符并将其移动到最前面或最后面。 每个动作都会将该角色从其位置中删除，并将其重新插入到两个极端之一。 

目标是转换初始字符串`s`进入目标字符串`t`使用最少数量的此类移动，或报告无法完成。 

一个关键的观察结果是该操作永远不会改变字符的多重集。 它只会排列它们。 这立即暗示了一个必要条件：两个字符串必须包含完全相同的字符数。 即使一个角色的频率有所不同，任何一系列的动作都无法修复它。 

约束很小，有`n ≤ 100`每次测试，最多 100 次测试。 这使得解决方案可以轻松地具有三次甚至二次行为。 然而，通过状态搜索来模拟任意重新排列的简单方法仍然是不必要的，因为操作的结构受到高度限制。 

天真的推理的一个微妙的失败案例是假设我们可以通过始终将下一个所需的字符直接移动到位来贪婪地从左到右匹配字符。 这忽略了一个事实，即移动的角色会影响相对顺序，从而可能迫使以后进行额外的移动。 

例如，考虑：`s = "abac"`

`t = "baca"`一个幼稚的策略可能会反复将正确的字符放在前面，但根据选择，您可能会过度计数或无法注意到更有效地使用后面插入的更好序列。 

正确的解决方案需要推理出有多少目标可以以反映允许的移动的结构化方式匹配为子序列。 

## 方法

 暴力解释是将每个字符串视为一个状态，将每个移动视为一条边，然后对可到达的排列运行最短路径搜索`s`。 由于每个州都有`O(n)`可能的动作有`n!`状态，即使对于小公司来说，这也是完全不可行的`n`。 

关键的结构见解是该操作仅提取单个字符并将其放置在一端。 这意味着字符已经以正确的相对顺序出现在`s`和`t`不一定需要移动。 问题在于如何保留尽可能多的顺序，同时仅“提取”放错位置的字符。 

我们可以反过来重新解释这个过程。 而不是建造`t`从`s`，我们尝试对齐`s`和`t`通过识别已经匹配的大中心部分`t`作为一个稳定的子序列。 该对齐区域之外的字符对应于必须执行的移动，并且每个移动通过将其推到末端来有效地修复一个放错位置的字符。 

这引出了核心思想：我们尝试匹配`t`反对`s`同时允许从两端删除，但最大限度地减少必须重新定位的字符数。 

一种简洁的查看方法是找到最长的子序列`t`当我们模拟转弯时，它可以保持在原位`s`进入`t`。 不在此保留结构中的每个字符都必须至少移动一次，并且该操作的结构确保可以通过一次移动独立解决每个此类不匹配。 

因此，答案简化为`n - L`， 在哪里`L`是在尊重可行性约束的情况下可以保持正确的相对顺序的最大字符数。 这相当于在只允许末尾插入的特殊限制下找到最长公共子序列，这会崩溃为贪婪的两指针匹配，计算有多少个字符`t`可以在里面按顺序对齐`s`经过优化调整后。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 字符串上的强力 BFS | O(n!·n) | O(n!·n) | O(n!) | 太慢了 |
 | 贪心子序列对齐 | 每次测试 O(n²) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 首先通过比较字符频率来验证可行性`s`和`t`。 如果它们不同，则答案是`-1`。 这是必需的，因为移动永远不会改变字符数。 
2. 使用两指针策略计算有多少个字符`t`可以按照里面的顺序进行匹配`s`同时模拟结构的最佳保留。 我们扫描通过`s`并尝试贪婪地匹配每个字符`t`为了。 
3. 每次找到匹配的字符时，我们都会将两个指针前移。 如果不匹配，我们只前进指针`s`。 这衡量了有多少`t`已经“嵌入”了`s`作为不需要重新排列的有序结构。 
4. 令该匹配长度为`L`。 其余`n - L`字符对应于必须使用允许的操作重新定位的元素。 每一个这样的不匹配都可以通过在适当的构建阶段将角色拉到正确的末端来一次解决。 
5、输出`n - L`作为最小移动次数。 

### 为什么它有效

 不变的是贪婪匹配计算最长的前缀一致嵌入`t`里面`s`可以在仅最终提取操作下生存。 不属于此嵌入的任何字符都必须至少跨越所保留结构的边界一次，并且每次移动都允许通过将单个字符重新定位到极端来精确地进行一次这样的校正。 由于移动不会干扰保留子序列内已经固定的相对顺序，因此解决两个不匹配问题比单独解决问题更便宜。 这使得计数变得紧张。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        s = input().strip()
        t = input().strip()

        if sorted(s) != sorted(t):
            print(-1)
            continue

        i = 0
        j = 0

        while i < n and j < n:
            if s[i] == t[j]:
                j += 1
            i += 1

        L = j
        print(n - L)

if __name__ == "__main__":
    solve()
```该解决方案首先检查两个字符串是否包含相同的多组字符。 考虑到小的限制，排序就足够了。 如果他们不同，我们会立即拒绝该案件。 

两指针循环计算有多少个字符`t`可以按照里面的顺序进行匹配`s`。 指针`i`扫描`s`， 尽管`j`跟踪进展`t`。 每场成功的比赛都会晋级，否则只能晋级`i`向前移动。 这产生了最长子序列的长度`t`发现于`s`。 

最后，答案计算为`n - L`，对应于必须主动移动到一端以实现完全对齐的字符。

 ## 边缘情况

 对于相同的字符串，例如`s = "aaaa"`，该算法正确计算零移动，因为频率匹配保持并且完整子序列对齐立即成功，给出`L = n`。 

对于完全反转的字符串，例如`s = "abcd"`,`t = "dcba"`，频率检查通过，但贪婪匹配几乎找不到对齐，从而产生很高的不匹配计数。 每个不匹配对应于一个必要的边界移动，并且算法正确地捕获每个字符必须至少重新定位一次。 

对于单字符字符串，匹配和频率检查都会崩溃为微不足道的结果，无需特殊处理即可确保正确性。
