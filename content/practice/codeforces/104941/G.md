 ## 解决方案
 ## 问题理解

 我们得到一个有向图，其中每个顶点最多有一个传入边和最多一个传出边。 这种限制意味着每个连通分量在结构上都非常简单：它要么是有向路径，要么是有向循环，并且没有顶点是分支点。 

每个顶点都有一个权重。 游戏从这个固定图开始，唯一允许的操作是添加更多有向边，但每次这样做时，我们都必须保留以下规则：没有顶点最终具有多于一条传出边且不超过一条传入边。 从顶点 u 到顶点 v 的每条新边都会给出 (w_u + w_v)^2 的分数，目标是最大化所有添加的边获得的总分数。 

关键的结构结果是初始图仅消耗每个顶点的一些“容量”。 顶点可能已经使用其传出槽、传入槽、两者或两者都不使用。 剩下的是空闲传出槽和空闲传入槽的集合，只要我们遵守一对一的约束，我们就可以任意连接它们。 

约束 n、m 高达 100000 意味着任何解决方案在实践中都必须本质上是线性的或接近线性的，并且可能具有 n log n 排序步骤。 任何关于顶点或边的二次方都是不可能的，因为它涉及大约 10^10 次运算。 

如果假设我们可以在不考虑全局结构的情况下贪婪地连接局部最佳对，则幼稚推理的微妙失败案例就会出现。 例如，如果我们有权重 [1, 10, 100, 1000] 和任意可用端点，那么如果单独考虑，将 1000 与 1 配对在本地看起来很有吸引力，因为它会产生一个大的平方项，但总体而言，最佳结构取决于所有顶点之间的一致配对，而不是单个边的贪婪性。 另一个问题是忽略容量对称性：如果我们忘记每个顶点最多贡献一个传入和传出槽，我们可能会尝试以违反可行性的方式匹配端点。 

## 方法

 直接强力方法会将每个可能的附加边视为候选边，并尝试选择尊重入度和出度约束的边子集。 这成为最大权重二分匹配问题，其中每个空闲传出时隙可以连接到每个空闲传入时隙，并且边权重为 (w_u + w_v)^2。 一个简单的实现会尝试所有配对，但是 k 个自由传出顶点和 k 个自由传入顶点之间可能的匹配数量为 k！，即使 k 约为 20，这也是不可行的。 

关键的观察结果是目标函数在展开时会大大简化。 对于任何选定的对 (u, v)，贡献为 w_u^2 + w_v^2 + 2 w_u w_v。 对所有匹配对进行求和，总数变为仅取决于所选集合的常数项加上仅取决于成对乘积的项。 常数部分不取决于我们如何配对顶点，只取决于匹配哪些顶点。 由于每个空闲传出时隙必须与一些空闲传入时隙相匹配，因此集合由初始图固定，并且优化完全简化为在两个多重集之间的完美匹配上最大化乘积 w_u w_v 的总和。 

这正是重排不等式适用的情况。 将最大权重与最大权重配对可以最大化乘积之和。 因此，对两侧进行排序并按顺序匹配它们会产生最佳结果。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力匹配| O(k!) | O(k) | 太慢了 |
 | 排序+贪婪配对| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

1. 计算初始图中每个顶点的当前入度和出度。 每个顶点的传入和传出边的容量都从 1 开始，因此我们确定有多少插槽可用于传出和传入连接。 
2. 构建两个列表，一个包含具有空闲传出槽的所有顶点，另一个包含具有空闲传入槽的所有顶点。 这种分离准确地表示了新边的起始位置和结束位置。 
3. 隐式验证两个列表的大小是否相同。 这是成立的，因为在任何有向图中，传入边的总数等于传出边的总数，因此总剩余容量也必须平衡。 
4. 按顶点权重降序对两个列表进行排序。 此步骤准备应用重排不等式的结构，确保高值顶点匹配在一起。 
5. 将输出列表中的第 i 个顶点与输入列表中的第 i 个顶点配对，并累积每对的贡献 (w_u + w_v)^2。 
6. 输出最终累加和。 

### 为什么它有效

 一旦我们确定了哪些顶点可以参与新的边，每个有效的解决方案都只是相同两个集合之间的排列配对。 展开平方表达式表明目标的配对相关部分正是 w_u w_v 的乘积之和。 为了最大化排列的总和，由于重排不等式，对两个序列进行排序并直接匹配它们是最佳的。 图的约束确保边之间没有超出度数限制的相互作用，因此没有额外的结构约束干扰这种减少。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    w = list(map(int, input().split()))

    indeg = [0] * n
    outdeg = [0] * n

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        outdeg[a] += 1
        indeg[b] += 1

    out_nodes = []
    in_nodes = []

    for i in range(n):
        if outdeg[i] == 0:
            out_nodes.append(i)
        if indeg[i] == 0:
            in_nodes.append(i)

    out_nodes.sort(key=lambda x: w[x], reverse=True)
    in_nodes.sort(key=lambda x: w[x], reverse=True)

    ans = 0
    for i in range(len(out_nodes)):
        u = out_nodes[i]
        v = in_nodes[i]
        ans += (w[u] + w[v]) * (w[u] + w[v])

    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先提取由初始图引起的剩余度数容量。 关键的一步是将“有效图”解释为严格的容量约束，而不是连接性的结构约束。 一旦做出解释，其余代码就简化为构建两个空闲端点列表。 

按权重对两个列表进行排序是执行优化原则的关键。 一个常见的错误是仅对一侧进行排序或尝试进行贪婪配对而不进行排序，这会破坏最优性。 

最后的循环直接计算贡献的平方。 在代码中不需要展开平方，因为 Python 可以安全地处理整数算术，并且保持表达式完整可以避免拆分项时出现错误。 

## 工作示例

 考虑一个具有三个顶点且没有初始边的小情况。 令权重为 [1, 3, 2]。 然后每个顶点都有一个空闲的传入和传出槽，因此两个列表是相同的。 

| 步骤| 出炉名单 | 在列表中 | 配对 | 部分总和|
 | ---| ---| ---| ---| ---|
 | 构建后 | [3,2,1]| [3,2,1]| - | 0 |
 | 对 1 | 3 与 3 | 3 与 3 | (3+3)^2 = 36 | 36 | 36
 | 配对 2 | 2 与 2 | 2 与 2 | (2+2)^2 = 16 | 52 | 52
 | 对 3 | 1 与 1 | 1 与 1 | (1+1)^2 = 4 | 56 | 56

 这表明排序对齐相同的量级并最大化每个产品的贡献。 

现在考虑一个受初始边约束的情况：假设顶点 1 指向 2，顶点 3 是孤立的，权重为 [5, 1, 4]。 顶点 1 没有传出容量，顶点 2 没有传入容量，而顶点 3 两者都有。 

| 顶点| 瓦 | 外帽 | 帽内|
 | ---| ---| ---| ---|
 | 1 | 5 | 0 | 1 |
 | 2 | 1 | 1 | 0 |
 | 3 | 4 | 1 | 1 |

 所以传出列表是 [2, 3]，传入列表是 [1, 3]。 按权重排序后，我们得到：

 | 配对| 贡献 |
 | ---| ---|
 | 3 → 1 | (4+5)^2 = 81 |
 | 2 → 3 | (1+4)^2 = 25 |

 总数变为 106，表明只有容量而不是原始结构影响配对。

 ## 边缘情况

 A corner case occurs when a vertex is both in the incoming and outgoing free sets. 对于孤立的顶点，会发生这种情况。 该算法自然地处理这个问题，因为相同的顶点可以出现在两个列表中，并且排序确保它与另一个顶点而不是其本身一致匹配。 

Another case is when the initial graph already forms a single directed cycle. Every vertex then has both in-degree and out-degree equal to 1, meaning no vertex is available for new edges. 两个列表都是空的，算法返回零而不尝试任何配对。 

另一种微妙的情况是权重高度倾斜，例如一个顶点与所有其他顶点相比具有极大的权重。 排序可确保该顶点与下一个最大的可用顶点配对，这正是最大化二次交互项的原因，并防止在多个小权重顶点之间进行次优分散。
