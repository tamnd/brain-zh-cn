 ## 解决方案
 ## 问题理解

 我们正在与一个选择了整数阈值的隐藏系统进行交互$C$介于 1 和$N$。 我们可以想到从 1 到$N$作为一条线上的位置，每次我们选择一个位置时，我们实际上都是在用那种颜色“染”头发。 在第一个选择之后，每个下一个选择都会与前一个选择进行比较，我们被告知两个所选数字之间的绝对差是否至少为$C$。 

关键机制是系统仅报告二进制信号：如果两个连续选择的值相距足够远，则表示 1，否则表示 0。 第一个查询很特殊，因为没有之前的颜色可供比较，因此它的答案不包含任何信息。 

任务是确定 的准确值$C$最多使用 64 次这样的比较。 

约束条件非常大，$N$最多$10^{18}$，这会立即排除任何试图一一探究值的策略。 即使是对整个范围进行对数扫描也需要小心，因为每个“测试”都是交互式的并消耗一个查询。 真正的限制不是算术复杂性而是查询预算，因此解决方案必须在每次交互中提取最大的信息。 

如果我们假设我们可以在不控制“先前值”的情况下独立测试任意对之间的比较，就会出现微妙的失败情况。 由于响应仅取决于连续的查询，而不是独立的对，因此任何将查询视为独立比较的天真的想法都会悄然崩溃。 

例如，如果我们尝试查询$x$以及稍后的查询$y$并假设我们正在测试$|x-y|$，除非我们仔细控制转换，否则这是不正确的，因为中间查询会覆盖以前的状态。 

## 方法

 蛮力策略会尝试发现$C$通过尝试增加距离并观察响应何时从 0 翻转到 1。在静态设置中，这类似于检查所有可能的值$d$从 1 向上，但在这个交互式模型中，每次检查都需要构造一对具有差异的有效数字$d$，并且重复这样做将需要线性时间$N$，这在时间和查询限制下都是不可能的。 

关键的观察是，每次交互都为我们提供了关于两个连续查询之间的间隙的确定性谓词。 如果我们可以强制系统始终将所选值与固定参考进行比较，那么每个查询都将成为一个干净的不等式测试$C$。 

这是通过锚定先前的值来实现的。 如果我们确保每个有意义的比较都是在选定的$x$和一个固定值 1，那么响应直接告诉我们是否$|x - 1| \ge C$。 这将问题转化为单调谓词$x$，允许二分查找。 

唯一剩下的困难是控制交互状态，以便每个测试确实进行比较$x$针对 1。这是通过在每次探测后插入“重置”查询到 1 来处理的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 远距离线性探测|$O(N)$查询 |$O(1)$| 不可能|
 | 带有重置查询的受控二分搜索 |$O(\log N)$查询 |$O(1)$| 已接受 |

 ## 算法演练

 我们保持不变，即在每个完成的测试周期后，最后选择的颜色为 1。 

1. 首先发送值为 1 的虚拟查询。这将初始化先前的颜色，但其响应将被忽略。 完成此步骤后，我们知道系统处于定义的状态。 
2. 我们为候选值定义一个类似函数的测试$x$，我们想知道是否$x - 1 \ge C$。 这相当于比较时检查系统是否响应1$x$与 1.
 3. 评估候选人$x$, 第一个查询$x$。 这将内部先前的颜色设置为$x$，但我们不使用此响应。 
4.立即查询 1.现在系统进行比对$x$与 1 并返回 1 当且仅当$|x - 1| \ge C$。 在这一步之后，之前的颜色恢复为 1，这保留了我们的不变量。 
5.我们二分查找最小的$x$在范围内$[2, N]$使得测试返回 1。这一点恰好是$x = C + 1$，因为低于该值的值未通过阈值，而从该点开始的值则通过阈值。 
6. 输出$C = x - 1$。 

二分查找是标准的：维持一个范围$[l, r]$，测试中点，并根据是否缩小范围$mid$满足谓词。 

### 为什么它有效

 核心不变量是每次有意义的比较总是在当前候选者之间进行$x$以及固定的基线值 1。因为每个测试中的第二个查询总是将系统重置回 1，所以跨步骤不会累积交互漂移。 

这确保了谓词“确实$x$在复位周期中产生响应 1”仅取决于$x$，而不是以前的历史。 这使得谓词单调$x$，从一次开始$x - 1 \ge C$成立，它适用于所有更大的$x$。 单调性保证了二分查找的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(x: int) -> int:
    print("?", x)
    sys.stdout.flush()
    return int(input().strip())

def solve_case(n: int):
    # establish initial state
    ask(1)

    def check(x: int) -> int:
        # query x, then reset with 1
        ask(x)
        return ask(1)

    l, r = 2, n
    ans = n

    while l <= r:
        mid = (l + r) // 2
        if check(mid):
            ans = mid
            r = mid - 1
        else:
            l = mid + 1

    print("=", ans - 1)
    sys.stdout.flush()

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        solve_case(n)

if __name__ == "__main__":
    main()
```实施围绕`check(x)`例程，它通过将每个候选查询与重置查询配对为 1 来强制进行受控比较。二分搜索仅对可安全用作候选的值进行操作，从 2 开始，因为 1 不会产生有意义的分离。 

最初的调用`ask(1)`为了确保第一个真正的比较行为一致，即使它的响应被丢弃，这是必要的。 

## 工作示例

 考虑$N = 7$和$C = 4$。 正确的转变点是$x = 5$。 

| 步骤| 查询 x | 查询1结果| 意义| 搜索范围 |
 | --- | --- | --- | --- | --- |
 | 1 | 4 | 0 | 3 < C 所以 x=4 失败 | [2, 7] |
 | 2 | 6 | 1 | 5 ≥ C+1 所以 x=6 次 | [2, 5] |
 | 3 | 5 | 1 | 边界仍然存在| [2, 4] |

 最后，最小的通过$x$是 5，所以$C = 4$。 

现在考虑$C = 1$，最小的可能值。 任何$x \ge 2$将立即通过测试，因此二分查找很快收敛到$x = 2$，产生$C = 1$。 

这些跟踪表明谓词的行为与排序数组上的阈值函数完全相同。

 ## 边缘情况

 当$C = 1$，不同数字之间的每次比较始终返回 1。该算法仍然有效，因为传递谓词的第一个值是$x = 2$，所以计算结果正确变为1。 

什么时候$C = N$，只有精确的差异$N$会通过，这是不可能的，所以每个测试都返回 0 直到$x = N$。 二分查找自然收敛于$x = N$，生产$C = N - 1$，它符合定义，因为只有区别$N-1$不足，所有其他都低于阈值。 

交互重置步骤在所有情况下都是必不可少的。 如果在每次探测后不将基线重新建立为 1，谓词就会变得依赖于路径，并且二分搜索会失去有效性，从而导致即使对于固定的响应也会不一致$x$。
