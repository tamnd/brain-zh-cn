 ## 解决方案
 ## 问题理解

 我们获得了一支足球队在一系列比赛中的汇总统计数据。 我们不知道单场比赛的结果，只知道三个数字：进行了多少场比赛、球队在所有比赛中的总进球数以及总失球数。 

任务是重建与这些总数完全匹配的任何有效的比赛得分线序列。 在所有可能的重建中，我们必须尽量减少平局的次数，平局意味着比赛结束时双方进球相同。 如果多次重建达到此最小值，则其中任何一个都是可以接受的。 

重新解释该问题的一个有用方法是，我们将一对整数（得分和失球总数）分成 n 个有序对。 每对代表一个比赛分数。 第一个分量的总和必须等于 a，第二个分量的总和必须等于 b。 目标是构建这些对，以便尽可能少的对满足两个组件之间的相等性。 

约束很小：n 最多为 100，总目标最多为 1000。这立即表明任何具有二次甚至仔细三次行为的解决方案都可以，而对匹配分布的指数搜索是不必要的。 真正的挑战不是计算复杂性，而是用受控数量的相等对构建有效的分解。 

当一个或两个总数为零时，就会出现微妙的边缘情况。 如果 a 等于 b，人们可能会试图将所有比赛都指定为平局，但这永远不是最佳的，除非受到不可分割性约束的强制。 另一种边缘情况是当 n 相对于总进球数较大时，例如 a = 1、b = 0、n = 100。许多比赛在至少一个坐标中不可避免地会出现 0:0 的情况，而粗心的贪婪分配可能会意外地引入不必要的平局。 

关键的困难是理解平局在结构上是如何产生的：平局在单场比赛中消耗相同数量的得分和失球，因此最小化平局意味着尽可能避免配对相等的分配，同时仍然尊重总数。 

## 方法

 强力解释将尝试在 n 场比赛中分配所有可能的进球分布，并计算每种配置的平局数。 即使我们离散每场比赛的进球数，每场比赛也可能有多达 1000 种进球和失球的可能性，因此状态空间非常大，大约为 1000^(2n)。 这是完全不可行的。 

关键的观察是我们没有优化匹配之间的排列或复杂的交互。 除了全局总和约束之外，每个匹配都是独立的。 这意味着我们可以贪婪地构建匹配，同时确保满足总数。 创建平局的唯一方法是有意分配一对 (x, x)，因此如果我们可以在尽可能多的比赛中避免相等，我们就可以最大限度地减少平局。 

该结构进一步简化：如果我们可以为所有匹配分配不同的 (x, y)，那么我们就可以实现零平局。 唯一一次我们被迫平局是当我们由于剩余的对称约束而无法避免 x = y 时。 然而，由于我们可以在比赛中任意分配进球数，因此我们总是可以避免创建相等的对，除非两个总数都在本地强制进行。 

一个干净的建设性策略是贪婪地分配所有匹配，同时确保除非必要，否则我们永远不会使匹配对称。 我们一次分配一场比赛的进球数，总是尝试为进球数和失球数分配不同的值。 如果在任何时候剩余总数相等，我们将使用平局比赛。 

这将问题简化为将两个和分成 n 对的受控贪婪划分，并优先考虑不相等的对。

 ## 算法演练

 我们按顺序构建比赛，同时跟踪剩余的目标。 

1. 开始时剩余进球数等于 a，失球数等于 b，并分配 n 场比赛。 我们将逐一构建每场比赛，确保总金额保持可行。 
2. 对于前 n − 1 场比赛中的每一场，我们尽量避免平局。 我们选择一个分数 (x, y)，使得 x 与 y 严格不同并且均为非负数，同时保持剩余总数可行。 一种简单的方法是分配最小的可能值，例如，如果 a > 0，否则设置 0，则设置 x = 1，并在可能的情况下以不同方式分配 y。 关键是要确保 x ≠ y，同时不要错误地穷尽总数。 
3. 分配非平局比赛后，我们从 a 中减去 x，从 b 中减去 y。 这保留了剩余总数仍然可以分布在剩余比赛中的不变性。 
4.最后一场比赛，我们必须用剩下的东西。 若剩余a等于剩余b，则本场比赛为平局； 否则，它是完全使用 (a, b) 的非绘制分配。 

最后一步是被迫的，因为我们必须完全满足两个总数。 任何不平衡都必须在那里得到解决。 

### 为什么它有效

 保持的不变性是，每次分配后，剩余的总进球数（a，b）仍然可以分配到剩余的比赛中，而不违反非负性。 由于我们从不过早地强制平等，因此我们只会在最后的剩余部分需要时才进行平局。 因此，抽签次数被最小化，因为任何抽签都准确地对应于在剩余状态下不可能进行不对称分配的情况。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = int(input())
    b = int(input())

    res = []

    # We try to distribute greedily
    for i in range(n - 1):
        if a > b:
            x = 1 if a > 0 else 0
            y = 0
        else:
            x = 0
            y = 1 if b > 0 else 0

        # fallback if both zero
        if a == 0 and b == 0:
            x, y = 0, 0

        res.append((x, y))
        a -= x
        b -= y

    # last match takes everything
    res.append((a, b))

    draws = sum(1 for x, y in res if x == y)

    print(draws)
    for x, y in res:
        print(f"{x}:{y}")

if __name__ == "__main__":
    solve()
```该结构使用简单的贪婪偏差：我们总是首先尝试减少较大的剩余总数，确保我们保持分布尽可能不对称。 最后一场比赛吸收了所有剩余的不平衡。 绘制计数是直接根据相等性检查计算的。 

一个微妙的点是，中间的比赛被迫进行极小的调整（0或1），这可以防止意外超出总数。 由于 n 最多为 100，总数最多为 1000，因此这种增量减少是安全的。

 ## 边缘情况

 当 n = 1 时，没有灵活性：单场比赛必须代表全部总数，并且当 a 等于 b 时恰好发生平局。 该算法自然会处理这个问题，因为跳过循环并且最终匹配是 (a, b)，因此可以正确检测到相等性。 

当a = b = 0并且n很大时，每个匹配都变成(0, 0)。 每场比赛都是平局，这是不可避免的，因为没有办法在不消耗进球的情况下引入不对称性。 

当 a 或 b 之一为零时，构造简单地将所有目标分配给一侧。 除非两个总数都为零，否则不会引入相等，因此平局计数保持最小。 

当总数很小但 n 很大时，许多比赛的贡献为零。 贪婪分配仍然有效，因为它只在可能的情况下进行减法，并且剩余分配对于最终匹配始终有效。
