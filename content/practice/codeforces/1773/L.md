 ## 解决方案
 ## 问题理解

 我们得到一个整数序列和固定长度$k$。 任务是尽可能少地修改序列，使其不再包含任何长度精确的连续块$k$那是单调的。 如果一个块完全不减或完全不增，那么它就是单调的。 

关键对象不是任意子序列，而是连续的段。 我们正在有效地扫描任何长度的窗口$k$其中值永远不会改变方向。 如果存在这样的窗口，则该序列被认为是“无聊的”，我们必须通过更改尽可能少的元素来破坏所有此类单调窗口。 

输出不仅是更改的数量，而且还是一个完全构造的修改数组。 每个更改的位置都必须与原始位置不同，并且我们必须确保没有长度-$k$单调的部分仍然存在。 

限制是极端的：$n$上升到$10^6$。 这立即排除了任何以二次甚至稍微超线性的方式独立检查所有窗口的解决方案。 任何正确的方法都必须是线性的或接近线性的，因为即使$O(n \log n)$在这种规模下，具有大量常量是有风险的。 

一种简单的方法是滑动一个大小的窗口$k$遍历数组并检查每个窗口的单调性$O(k)$，导致$O(nk)$。 和$n = 10^6$，这变得完全不可行。 

当数组到处都“几乎单调”时，就会出现微妙的边缘情况，例如严格递增的序列。 在这种情况下，每个窗口都是坏的，天真的策略会尝试独立修复重叠的窗口，从而导致冗余的更改。 另一个棘手的情况是交替序列，其中只有一些窗口是单调的，这可能会引发贪婪的本地修复，从而意外地在其他地方创建新的单调窗口。 

真正的困难在于变化在全球范围内相互作用：修复一个窗口会影响许多其他窗口。 

## 方法

 暴力策略将检查每个长度的子数组$k$并检查它是非减少还是非增加。 如果发现一个坏窗口，我们可以尝试修改其中的一个元素。 然而，这立即变得不明确：更改一个元素可能会修复当前窗口，但会创建新窗口，并且重复重新计算所有内容会导致级联重新计算成本。 

暴力正确性很简单，因为它明确地检查所有禁止的模式，但它在性能和重叠窗口之间的交互控制方面失败。 每个职位最多参与$k$windows，因此重复的修复很快就会爆炸。 

关键的见解是停止从窗口角度思考，而是从防止局部结构中长时间单调运行的角度思考。 长度-$k$单调段意味着在那些$k-1$相邻比较，所有符号都相同。 这意味着我们实际上是在控制连续“同方向”比较的序列。 

我们可以强制任何连续的非递减或非递增关系在达到长度之前被破坏，而不是显式地跟踪每个窗口$k-1$。 这将问题转化为管理派生的比较序列中的运行。 

最优策略变成贪心：我们从左到右扫描，维持当前方向的游程长度，每当快要到达的时候$k-1$，我们通过修改当前元素来强制改变数组以打破单调性。 由于我们总是在违规发生之前中断，因此我们保证不会形成禁止窗口。

 | --- | --- | --- | --- |
 | 蛮力 |$O(nk)$|$O(1)$| 太慢了|
 | 最佳 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们在从左到右扫描的同时构建最终的数组，跟踪最后的运动方向以及当前单调运行持续了多长时间。 

1. 初始化工作数组$a$作为输入的副本，并为当前单调游程长度设置一个计数器。 

游程长度测量方向不改变的连续比较。 
2. 对于每个位置$i$从 1 到$n-1$，计算是否$a[i]$继续之前的方向（与之前相比增加或减少$a[i-1]$）。 
3. 如果方向与上一步一致，则增加游程长度。 否则将其重置为 1。 

这是追踪我们离形成单调段的距离有多近。 
4. 如果游程长度达到$k-1$，我们处于危险状态：下一步可能会创建一个长度单调的段$k$。 
5.为了防止这种情况，我们修改$a[i]$从而打破当前的方向。 我们选择一个与邻居不同的值，确保它不会继续单调。 修改后，重新设置游程长度。 
6. 继续扫描直至结束。 

这种结构确保我们只在绝对必要时才更改元素，这就是极简主义的产生方式。 

### 为什么它有效

 该算法强制执行不变量，即没有序列$k-1$连续的比较具有相同的符号。 任意单调长度段$k$在比较中就意味着这样的运行，因此防止长运行可以直接防止禁止的段。 因为我们只在最后可能的时刻进行干预，所以每次更改都恰好消除了一个潜在的违规行为，而不会引入不必要的额外更改。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    changes = 0

    # we will track run length of monotone direction
    run = 1
    direction = 0  # 1 increasing, -1 decreasing, 0 unknown

    for i in range(1, n):
        cur_dir = 1 if a[i] > a[i-1] else (-1 if a[i] < a[i-1] else 0)

        if cur_dir == direction and cur_dir != 0:
            run += 1
        else:
            direction = cur_dir
            run = 1

        if run >= k - 1 and direction != 0:
            # force break monotonicity at position i
            changes += 1

            # pick a value that breaks both sides if possible
            left = a[i-1]
            right = a[i+1] if i + 1 < n else left + 1

            # ensure a[i] is different and breaks direction
            if direction == 1:
                a[i] = min(left, right) - 1
            else:
                a[i] = max(left, right) + 1

            # reset state after modification
            run = 1
            direction = 0

    print(changes)
    print(*a)

if __name__ == "__main__":
    solve()
```该实现维护对数组的单次传递。 运行逻辑跟踪我们是否正在扩展单调趋势。 当我们检测到即将达到禁止阈值的运行时，我们立即覆盖当前元素。 

一个微妙的点是重置价值的选择。 我们必须确保它与原始版本不同，并打破相对于邻居的单调性。 使用小于两个邻居或大于两个邻居的值可保证至少一个相邻比较翻转方向，从而安全地重置运行。 

我们还在修改后重置了状态，因为局部结构已被故意破坏。

 ## 边缘情况

 关键边缘情况是完全单调的序列，例如$1,2,3,4,5$与小$k$。 如果没有干预，每个窗口都是无效的。 该算法通过在游程长度即将达到时准确插入中断来修复此问题$k-1$，确保即使是密集的单调序列也能尽早破碎。 

另一个边缘情况是重复值。 由于相等不会影响增加或减少方向，因此运行会自然重置，从而防止误报。 该算法正确地将相等的段视为中性中断，从而减少了不必要的修改。 

最后一个微妙的情况是修改将约束传播到邻居。 由于每个修复都会重置本地方向状态，因此不会错误地累积修改链，并且每个强制中断都会隔离未来的决策。
