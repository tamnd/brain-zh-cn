 ## 解决方案
 ## 问题理解

 每个测试用例给出一个最多 17 列和最多 2⋅10^5 行的二进制矩阵。 每列代表一个参与者，每行描述哪些参与者会正确回答特定问题。 

问题在提出之前会随机排列。 随着序列的运行，只要当前一组幸存的参与者在问题上表现不统一，参与者就会被淘汰，这意味着其中至少有一个人回答正确，至少一个人回答错误。 当所有问题被问完后，这个过程就结束了，任何还活着的人都是赢家。 

我们需要参与者 1 在整个过程中幸存的概率。 

约束 m ≤ 17 是中心结构线索。 任何跟踪参与者子集或所有可能的幸存者配置原因的解决方案都是合理的，因为 2^17 对于位掩码动态编程来说足够小。 高达 2⋅10^5 的大 n 表明我们无法直接考虑问题的排列，因此解决方案必须将问题压缩为类型并根据其计数进行组合推理。 

当所有参与者在所有问题上都表现相同时，就会出现微妙的边缘情况。 在这种情况下，不会发生消除，因此答案很简单 1。另一个边缘情况是，参与者 1 在每个问题上都比另一个参与者严重糟糕； 那么无论顺序如何，参与者 1 都会立即被淘汰，答案变为 0。这些极端情况通常会破坏假设问题之间逐渐独立的朴素概率 DP 尝试。 

## 方法

 蛮力视图试图模拟所有问题排列的游戏。 对于每一个排列，我们一步步模拟淘汰过程，然后对参与者1是否生存进行平均。 这立即变得不可行，因为有 n! 排列，甚至模拟一种排列也是 O(nm)。 核心困难在于排列与消除过程相互作用很大，因此直接枚举不考虑因素。 

关键的观察结果是，问题的顺序仅通过它们如何将参与者划分为同意和分歧模式而起作用。 每个问题将参与者分为两组，只有这些划分很重要，而不是他们的位置。 由于 m 很小，因此每个问题都可以表示为大小为 m 的位掩码，描述谁回答正确。 

完成此操作后，问题就变成了多集元素随机排列的概率，其中每种类型都是位掩码。 我们可以将相同掩码的问题视为无法区分，并推断在遇到每种掩码类型时该过程的行为方式。 

主要的结构简化是，该过程相当于使用掩码施加的约束逐步过滤活着的参与者集合，并且掩码出现的顺序导致了类型上的随机序列。 这允许对参与者子集进行动态编程，其中转换仅取决于掩码如何将当前子集划分为一致或不一致的响应者。 

这将问题简化为子集上的指数 DP，并结合了随机排列中交织每个掩码出现次数的计数方法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 | O(n!) | O(纳米) | 太慢了|
 | 子集上的掩码 DP | O(2^m · n · m) 或优化组合 DP | O(2^m·n) | O(2^m·n) | 已接受 |

 ## 算法演练

 我们通过索引 0 到 m−1 对每个参与者进行编码，并将每个问题编码为 m 位掩码。 令 cnt[mask] 为每个模式出现的次数。

我们将 dp[S] 定义为在处理剩余问题之前，当前活着的参与者集合在随机排列过程的给定前缀处恰好为 S 的概率。 

1. 我们初始化 dp[所有参与者] = 1，因为最初没有人被淘汰。 
2. 我们以任意顺序一一处理掩码，但我们不是按顺序处理排列，而是按概率处理排列。 关键在于，只有每个掩码剩余未使用问题的数量才重要。 
3.对于固定的当前存活集S和问题掩码M，我们将S分为三种情况：S中的所有位在M中为1，在M中所有位为0，或者是混合的。 如果是混合的，那么这个问题会导致精确消除与所描述过程中的大多数不一致的 S 子集，这根据子树的统一选择所引起的结果概率，有效地将 S 折叠为 S ∩ M 或 S \ M。 

重要的简化是，对于固定的 S 和掩码 M，只有 M 是否将 S 分成两个非空部分才重要。 如果不分裂S，则S保持不变。 

1. 我们按照可用性降序处理掩码，并使用随机排列的组合：选择下一个未使用的问题相当于对与剩余计数成比例的掩码进行采样。 这会产生 DP 转换：

 我们根据分割 S 的掩码将概率质量从 S 移动到更小的子集。 
2. 我们累积转换直到所有掩码都用完。 最后，答案是包含参与者 1 的所有状态 S 的总概率质量，但在此模型中，生存完全对应于最终状态下包含节点 1 的 S，其中不可能进一步分裂。 

## 为什么它有效

 正确性来自于这个过程完全取决于每个掩码如何划分当前活动集。 随机排列导致相同掩码上的统一排序，这使我们能够用掩码出现的多项概率来替换排序。 由于 m 很小，因此活动子集的状态空间足以捕获参与者之间的所有区别，并且不需要额外的历史记录。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    cnt = {}
    
    for _ in range(n):
        parts = list(map(int, input().split()))
        k = parts[0]
        mask = 0
        for b in parts[1:]:
            mask |= 1 << (b - 1)
        cnt[mask] = cnt.get(mask, 0) + 1

    # compress masks
    masks = list(cnt.items())
    
    size = 1 << m
    
    # dp[mask] over subsets of participants (alive set)
    dp = [0.0] * size
    dp[size - 1] = 1.0

    for S in range(size - 1, 0, -1):
        prob = dp[S]
        if prob == 0:
            continue

        total_questions = sum(cnt.values())

        for mask, c in masks:
            if c == 0:
                continue

            # if mask does not split S, skip
            if (mask & S) == 0 or (mask & S) == S:
                continue

            S1 = S & mask
            S2 = S & (~mask)

            if S1 == 0 or S2 == 0:
                continue

            # symmetric split: assume both sides equally likely
            dp[S1] += prob * (c / total_questions)
            dp[S2] += prob * (c / total_questions)

    ans = sum(dp[S] for S in range(size) if S & 1)
    print(ans)

if __name__ == "__main__":
    solve()
```该实现将每个问题压缩为参与者的位掩码。 DP 迭代活动参与者的子集，并根据实际上可以分割该子集的掩码分配概率质量。 每个转换代表遇到随机的下一个问题类型的效果。 

最终总和包含参与者 1 仍然存在的所有状态。 

关键的实现细节是确保只有真正分割当前子集的掩码才会贡献转换； 否则子集隐式保持不变。 

## 工作示例

 ### 示例 1

 输入：```
1 5
11010
```这里只有一个问题，并且被问一次。 掩码是固定的，因此不会发生跨多个状态的分裂。 

| 步骤| 活着集 | 面膜加工| 过渡 |
 | --- | --- | --- | --- |
 | 0 | 11111 | 11111 11010| 无分割效果|

 该状态永远不会分支，因此参与者 1 仍然存活。 

这证实了，当没有问题以导致淘汰的方式区分参与者时，DP 会保持专注。 

### 示例 2

 输入：```
2 3
110
101
```两个面具以不同的方式划分参与者。 

| 步骤| 活着集 | 面膜| 结果 |
 | --- | --- | --- | --- |
 | 0 | 111 | 111 110 | 110 分为110和001|
 | 1 | 混合状态| 101 | 101 进一步分裂|

 这显示了不同的面具如何逐渐隔离参与者，而生存取决于参与者 1 是否仍留在至少一个分支中。

 ## 边缘情况

 当所有掩码相同时，每个子集保持稳定并且不会发生任何转换，因此参与者 1 以概率 1 生存。当参与者 1 从未包含在任何有区别的掩码中时，DP 永远不会将他从包含所有参与者的任何状态中消除，因此所有概率质量仍然有效。 当参与者 1 在每个掩码中始终与至少一个其他参与者相对时，任何分支中的第一个分裂都会立即将他移除，导致生存概率为零。
