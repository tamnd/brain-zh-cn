 ## 解决方案
 ## 问题理解

 我们得到了几个垂直堆叠的唯一编号的块。 每个堆栈都是从上到下排序的，我们可以使用两种操作来物理地重新组织这些块：我们可以通过采用前缀或后缀段并将其转换为新的堆栈来将堆栈切成两部分，或者我们可以通过将一个堆栈完全放在另一个堆栈的顶部同时保留内部顺序来合并两个堆栈。 

目标是最终得到一个堆栈，其中包含按数字标签从上到下递增顺序排序的所有块。 成本是拆分和合并操作的数量，我们必须最小化操作总数，报告最佳计划中使用了多少次拆分和多少次合并。 

关键的困难在于块最初被分组为任意堆栈，并且我们只能通过切割连续的前缀和连接堆栈来重新排列。 我们不允许任意重新排序各个块。 

数据总量的限制很小，总共最多 10,000 个块。 这排除了对重型数据结构或高级图形算法的任何需求。 围绕排序加上线性扫描的解决方案就足够了。 任何比 O(n log n) 更糟糕的事情都是安全的，甚至 O(n^2) 也可能生存，但没有必要。 

当块已经处于正确的全局顺序但分布在许多堆栈中时，就会出现一个幼稚但重要的失败案例。 总是合并相邻堆栈而不考虑全局顺序的贪婪合并策略可能会引入不必要的拆分或合并。 

例如，考虑堆栈`[1, 4]`,`[2, 3]`。 简单的策略可能会直接合并它们，但顺序约束需要拆分以隔离与排序顺序匹配的段，否则堆栈内的相对顺序会阻止正确的构造。 这表明我们必须推理全局顺序与堆栈边界的一致位置，而不是仅仅独立地处理堆栈。 

另一种边缘情况是当块在单个堆栈内形成已排序的序列时。 那么根本不需要拆分或合并。 任何总是执行至少一项操作的算法都是不正确的。 

## 方法

 蛮力方法试图模拟整个过程。 我们考虑每个可能的拆分和合并序列，将堆栈的每个配置视为一种状态。 从每个状态，我们生成所有有效的分割和合并，并运行最短路径搜索，直到达到排序的单堆栈配置。 

这是正确的，因为每个操作在结构空间中都是可逆的，并且我们探索所有可能性。 然而，国家空间是巨大的。 即使有 10,000 个块，将块划分为有序堆栈的数量也会组合增长，使得这种方法即使对于 20 个块也是不可行的。 

关键的观察是我们实际上不需要模拟任意配置。 最终配置已完全确定：按值排序的单个堆栈。 每个块最终都必须按照递增顺序相对于其他块放置，因此唯一真正的问题是初始堆栈如何与排序顺序相交。 

如果我们想象按值对所有块进行排序，则每个初始堆栈都是一个出现在该排序排列中的序列，但被分成了多个段。 唯一有用的结构属性是排序顺序中的连续元素是否已经以正确的邻接方式出现在同一堆栈中。 每当全局排序顺序中的两个连续元素尚未位于具有正确邻接关系的同一堆栈中时，我们必须执行合并边界交叉，并且每当堆栈包含属于不同排序段的元素时，我们必须进行拆分。 

因此，问题简化为跟踪排序顺序如何在初始堆栈中划分，并计算连续排序元素之间存在多少个“中断”。

 ## 算法演练

 1. 压平所有块，同时记住每个块来自哪个原始堆栈，并按值对它们进行排序。 

这为我们提供了我们想要实现的正确的最终顺序。 我们还保留堆栈 ID，以便我们可以比较原始配置中的邻接结构。 
2. 扫描排序列表并根据相邻元素的原始堆栈标识进行比较。 

每当按排序顺序的两个连续元素来自不同的堆栈时，我们就记录一个边界。 这些边界代表了我们在不进行合并操作的情况下无法直接保留邻接关系的地方。 
3. 计算按排序顺序相邻元素来自不同堆栈的次数。 调用这个值`k`。 

每个这样的边界强制至少一个合并操作来连接属于不同原始堆栈的段。 
4. 现在考虑拆分。 对于每个原始堆栈，按排序顺序查看其块。 

如果一个堆栈在全局排序顺序中贡献了多个不相交的段，则该堆栈必须至少被拆分那么多次减一。 对于每个堆栈，我们计算其元素按排序顺序形成多少个连续段，并累积所需的分割。 
5. 最终答案是所需拆分和所需合并的总和。 

重要的设计选择是我们从不显式模拟操作。 我们只计算初始分区和目标排序顺序之间的结构不一致。 

### 为什么它有效

 排序顺序定义了唯一的目标线性排列。 任何有效的构建过程最终都必须组装这个精确的序列。 每个初始堆栈要么贡献该序列的连续段，要么不贡献。 如果没有，则需要进行拆分来隔离段。 如果排序顺序中的两个连续元素来自不同的堆栈，则如果没有合并操作桥接它们的堆栈，它们就无法变得相邻。 由于操作仅连接或剪切连续的块，因此这两种类型的校正都是必要且充分的，并且没有任何操作可以在不明确解决的情况下一次修复多个这样的结构不匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = []
    stack_id = []
    
    for i in range(n):
        tmp = list(map(int, input().split()))
        k = tmp[0]
        for x in tmp[1:]:
            arr.append(x)
            stack_id.append(i)
    
    # sort by value
    order = sorted(range(len(arr)), key=lambda i: arr[i])
    
    # count merge boundaries
    merges = 0
    for i in range(len(order) - 1):
        if stack_id[order[i]] != stack_id[order[i + 1]]:
            merges += 1
    
    # count splits per stack via segment counting
    pos_in_sorted = [[] for _ in range(n)]
    for idx in order:
        pos_in_sorted[stack_id[idx]].append(idx)
    
    splits = 0
    for i in range(n):
        if not pos_in_sorted[i]:
            continue
        # count number of contiguous runs in sorted index space
        cnt = 1
        for j in range(1, len(pos_in_sorted[i])):
            if pos_in_sorted[i][j] != pos_in_sorted[i][j - 1] + 1:
                cnt += 1
        splits += cnt - 1
    
    print(splits, merges)

if __name__ == "__main__":
    solve()
```该实现首先将所有堆栈展平为单个列表，同时存储每个元素所属的原始堆栈。 按块值排序重建最终目标顺序。 

合并计数是通过扫描此排序顺序中的相邻元素并检查它们是否来自不同的堆栈来计算的。 每个这样的转变都指示必要的合并边界。 

通过查看其元素出现在排序数组索引空间中的位置来计算每个堆栈的拆分。 每当堆栈的元素在此空间中不连续时，就意味着堆栈在最终顺序上被分段，从而强制拆分以隔离每个连续的段。 

一个微妙的点是我们并不试图模拟实际操作。 正确性纯粹来自于计算诱导排列中的结构不连续性。

堆栈 0 显示为连续段`[3,5,8]`，无需拆分。

每个堆栈都有一个元素，因此不会分裂。 

结果是`0 2`。

 ## 边缘情况

 一种边缘情况是所有块已经形成完美排序的单个堆栈。 排序顺序与原始顺序一致，因此每个元素在正确的堆栈中相邻，并且不会发生转换。 该算法产生零分割和零合并，因为排序邻接扫描中没有堆栈变化，并且每个堆栈恰好贡献一个连续段。 

另一个边缘情况是每个块都在自己的堆栈中。 在这种情况下，按排序顺序的每个邻接都来自不同的堆栈，因此合并计数变为 n 减 1。每个堆栈只有一个元素，因此不存在内部碎片，并且拆分保持为零。 该算法正确地将问题简化为构建合并链。 

最后一个微妙的情况是，单个堆栈按排序顺序与其他堆栈严重交错。 即使它在输入中看起来是连续的，它的元素也可能分散在排序的排列中，从而强制进行多次分割。 段计数步骤检测其排序索引列表中的每个不连续性，并正确考虑所需的分割操作。
