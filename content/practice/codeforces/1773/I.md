 ## 解决方案
 ## 问题理解

 我们正在与一个隐藏的整数交互$n$，但我们不可以直接看到它。 相反，我们可以提出最多 10 个以下形式的问题：“什么是$k$从右边数第 - 位数字$n!$十进制表示形式？”。如果由于阶乘太短而导致该数字不存在，则系统返回 0。

 我们的任务是确定$n$对于使用这些数字查询的每个测试用例。 的价值$n$保证位于 1 到 5982 之间，阶乘的十进制表示形式在 20000 位以内。 

关键的困难是我们没有观察到$n!$直接地。 我们仅对其数字数组进行随机访问查询，但仅从最低有效侧开始，并在长度之外截断为零。 这意味着我们正在有效地探测一个大整数，其大小增长得非常快$n$，并且我们必须使用最多 10 位数字读取来区分大约 6000 个可能的值。 

约束条件$n \le 5982$是关键的结构提示。 这意味着直接模拟或重构阶乘是不可能的。 均匀收纳$n!$对于所有候选者来说已经太大了，因为阶乘增长超过 20000 位，并且在许多候选者之间重复比较字符串在多达 100 个测试用例中会太慢。 

天真的尝试会尝试每个候选人$n$, 计算$n!$，并检查与查询的一致性。 这会立即失败，因为计算高达 5982 的阶乘已经很昂贵，并且每个测试用例重复执行此操作是不可行的。 

第二个天真的想法是使用查询逐位重建完整的阶乘。 但由于我们只得到 10 个查询，并且可能的位数为 20000，因此我们无法恢复完整的数字。 相反，我们必须提取一个唯一标识的小签名$n$。 

尾随零会产生微妙的边缘情况。 由于因子 2 和 5，阶乘会累积许多尾随零。这意味着许多位置的最低有效数字大多为零，因此在数字末尾附近进行简单探测不会产生任何信息。 只查询像 0、1、2 这样的小索引的粗心策略将无法区分大索引$n$，因为所有阶乘都以长串零结尾。 

## 方法

 蛮力视角首先想象我们可以计算或查询足够多的$n!$来唯一地识别它。 如果我们有完整的数字，我们可以预先计算从 1 到 5982 的所有阶乘并比较数字字符串。 这是合乎逻辑的，因为阶乘的大小严格递增，因此每个$n$产生独特的数字模式。 

然而，这会失败，因为我们无法交互式地构建或比较完整的阶乘。 即使我们离线预先计算它们，交互模型也只允许每次测试 10 位数字查询，因此我们无法检索足够的信息来匹配完整的字符串。 

关键的观察结果是阶乘在其尾随零模式的结构和低位数字的分布方面存在显着差异。 虽然尾随零在索引 0 附近没有提供任何信息，但稍微进一步探究该数字会发现稳定的非零数字，这些数字在$n$。 挑战减少到找到一小组数字位置，为每个数字位置形成唯一的签名$n$。 

自从$n$范围最多只能达到6000左右，我们可以离线预先计算所有阶乘一次，存储它们的数字数组，然后模拟哪些数字位置最能区分值。 然后，在交互过程中，我们准确查询这些职位并与候选人进行匹配。 

这将问题转化为根据数字位置构建决策树。 每个查询都会减少候选集。 通过 10 个查询，我们可以将 6000 个候选数减少到单个值，因为每个数字查询将候选集最多分为 10 个组。

 | --- | --- | --- | --- |
 | 每次测试时强力重新计算阶乘 |$O(T \cdot n)$阶乘工作 |$O(1)$| 太慢了|

 ## 算法演练

 我们在本地数组中预先计算一次从 1 到 5982 的阶乘，以相反的顺序存储数字，因此索引直接对应于查询索引。 

然后我们模拟交互如下：

 1. 预先计算列表中最多 5982 的所有阶乘，其中每个条目以相反的顺序存储数字。 

这为我们提供了所有可能的隐藏数字的完整确定性知识。 
2. 从包含所有值的候选集开始$n \in [1, 5982]$。 
3. 对于最多 10 个查询中的每一个，选择一个数字位置$k$最好地分割当前候选集。 

目标是选择一个位置，使候选值产生不同的数字，而不是由零主导。 
4. 向法官询问数字$k$，接收一个值$d$。 
5. 通过仅保留那些来过滤候选集$n$使得位置处的预先计算的数字$k$在$n!$等于$d$。 
6. 重复直到候选集大小为 1。 
7. 输出剩余的候选作为答案。 

关键的设计选择是查询选择。 由于我们控制要询问的数字索引，因此我们选择使剩余候选者的熵最大化的索引。 由于尾随零，靠近最低有效数字的早期位置通常是无用的。 更好的位置位于阶乘变得稳定并且非零数字频繁出现的点附近。 

### 为什么它有效

 正确性依赖于以下事实：映射来自$n$一旦选择了足够的位置，所选位置处的数字向量就是内射的。 每个查询通过精确的数字相等来划分候选空间，并且由于阶乘是不同的整数，因此它们的数字表示至少在一个位置上不同。 通过自适应索引选择，每个查询都会减少歧义，直到只剩下一个候选者。 该过程保证在 10 个查询内终止，因为候选空间大小最多为 6000，并且可以选择每个查询对其进行有意义的分割。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXN = 5982

# Precompute factorial digits (reversed)
fact = [[1]]
for i in range(2, MAXN + 1):
    prev = fact[-1][:]
    carry = 0
    for j in range(len(prev)):
        x = prev[j] * i + carry
        prev[j] = x % 10
        carry = x // 10
    while carry:
        prev.append(carry % 10)
        carry //= 10
    fact.append(prev)

def digit(n, k):
    if k < len(fact[n - 1]):
        return fact[n - 1][k]
    return 0

def pick_best(cands, used):
    best_k = 0
    best_score = -1

    for k in range(20000):
        if k in used:
            continue
        seen = set()
        for n in cands:
            seen.add(digit(n, k))
            if len(seen) > 5:
                break
        score = len(seen)
        if score > best_score:
            best_score = score
            best_k = k
        if best_score == 10:
            break

    return best_k

def solve_case():
    cands = list(range(1, MAXN + 1))
    used = set()

    for _ in range(10):
        if len(cands) == 1:
            break

        k = pick_best(cands, used)
        used.add(k)

        print("?", k, flush=True)
        d = int(input().strip())

        cands = [n for n in cands if digit(n, k) == d]

    print("!", cands[0], flush=True)

def main():
    t = int(input())
    for _ in range(t):
        solve_case()

if __name__ == "__main__":
    main()
```该解决方案依赖于预先计算阶乘数字一次，然后将每个查询视为过滤候选者的约束。 这`pick_best`函数贪婪地选择一个数字位置，使剩余候选者之间观察到的变化最大化。 

过滤步骤是精确的，因为阶乘数字是确定性地预先计算的，因此每个查询都会与隐藏数字一致地减少候选集。 

使用反向数字存储可确保直接索引$k$，首先匹配最低有效数字的交互定义。

 ## 边缘情况

 关键的边缘情况是所有查询的位置都位于尾随零内。 例如，查询许多候选者的 k = 0 或 k = 1 会产生相同的答案。 该算法通过根据观察到的方差选择索引来避免这种情况，确保它最终进入有意义的数字区域。 

另一种边缘情况发生在小$n$，其中阶乘长度很短。 在这些情况下，任何超出数字长度的查询都会返回 0，但由于小阶乘在前面的数字中变化很快，因此在前几次查询后候选集仍然会正确收缩。 

对于大型$n$，数字稳定在中间位置。 该算法通过逐步向上移动查询索引来处理这一问题，确保至少一个查询位于阶乘表示在候选者之间显着不同的区域。
