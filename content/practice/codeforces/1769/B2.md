 ## 解决方案
 ## 问题理解

 我们被要求模拟将多个文件按顺序从一台服务器复制到另一台服务器，以两种方式跟踪进度：每个文件和整体。 每个文件都有一个字节大小，我们模拟逐字节复制。 每时每刻，我们都可以计算当前文件完成的整数百分比，以及所有文件完成的整数百分比。 我们的任务是找到在某个时刻同时出现在两个进度条上的从 0 到 100 的所有百分比。 

输入给出文件数量及其大小列表。 输出全是整数`p`这样`p%`两个条同时发生。 文件大小可能非常大，最多 10^10 字节，因此模拟每个字节是不可行的。 我们需要一种方法来计算可能的同时百分比，而无需迭代每个字节。 

主要限制是文件大小较大以及需要考虑向下舍入百分比。 例如，在一个文件中复制 6 个字节会生成每个文件的百分比 0、16、33、50、66、83、100。由于文件大小不同，每个文件的百分比不一定与总进度百分比一致，从而产生了我们需要捕获的间隙和重叠。 简单的模拟将执行最多 10^12 个步骤，这是不可能的，因此我们需要一种数学方法。 

不明显的边缘情况包括单个文件（所有百分比与总进度一致）、非常小的文件或大小不是 100 倍数的文件。例如，单个 6 字节文件具有上述百分比，算法必须正确检测每个同时发生的百分比，而不是假设统一的 1% 步长。 

## 方法

 暴力方法将迭代每个文件的每个字节，计算两个进度条并在它们重合时收集百分比。 这对于小输入是正确的，但很快就会变得不可行，因为大小为 10^10 的单个文件将需要 10^10 次迭代。 

关键的见解是，我们只关心任一进度条发生变化的时刻，这种变化发生在`a_i / 100`每个文件的百分比和`total_size / 100`为总体百分比。 由于使用向下舍入，因此映射到给定百分比的字节范围形成连续的间隔。 对于每个文件，我们可以计算与每个文件百分比相对应的字节范围。 同样，我们可以计算每个总体百分比的字节范围。 这些范围的交集给出了同时出现的一组百分比。 

从数学上来说，对于文件`i`尺寸的`a_i`从字节偏移量开始`offset`, 每个文件的百分比`p`发生于以下字节：`ceil(p * a_i / 100)`到`floor((p + 1) * a_i / 100) - 1`。 总体百分比`p`发生于以下字节：`ceil(p * total_size / 100)`到`floor((p + 1) * total_size / 100) - 1`。 如果这些间隔重叠，`p`是有效的同时百分比。 这将问题从模拟每个字节减少到为每个文件处理最多 101 个百分比值，这是可行的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(总和(a_i)) | 奥(101) | 太慢了|
 | 最佳 | O(n * 101) | 奥(101) | 已接受 |

 ## 算法演练

 1. 计算所有文件的总大小。 这定义了总体进度百分比的范围。 
2. 初始化一个空集来存储同时出现的百分比。 
3. 初始化变量`offset = 0`跟踪总数中每个文件的起始字节索引。 
4. 迭代每个文件`i`有尺寸`a_i`。 
5. 对于每个可能的每个文件百分比`p`从 0 到 100，计算显示该百分比的文件的第一个和最后一个字节。 第一个字节是`ceil(p * a_i / 100)`最后一个字节是`floor((p + 1) * a_i / 100) - 1`。 跳过与该文件中任何字节不对应的百分比。 
6.对于同样的`p`，计算总进度条中显示百分比的字节间隔`p`。 第一个字节是`ceil(p * total_size / 100)`最后一个字节是`floor((p + 1) * total_size / 100) - 1`。 
7. 如果每个文件的字节间隔和整体字节间隔重叠，则`p`是可以同时实现的。 添加`p`到集合。 
8. 更新`offset += a_i`移动到下一个文件的起始位置。 
9. 处理完所有文件后，排序并输出这组百分比。 

为什么它有效：每个文件和整体进度百分比在离散字节边界处发生变化。 通过计算每个整数百分比的间隔并检查重叠，我们捕获所有可能的同时显示，而不会因舍入而丢失任何内容。 考虑每个有效的百分比，并且舍入保证整数计算是足够的。 

## Python 解决方案```python
import sys, math
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

total = sum(a)
ans = set()
offset = 0

for size in a:
    for p in range(101):
        # per-file interval
        file_l = (p * size + 99) // 100  # ceil division
        file_r = ((p + 1) * size) // 100 - 1
        if file_l > file_r:
            continue
        # overall interval
        total_l = (p * total + 99) // 100
        total_r = ((p + 1) * total) // 100 - 1
        # shift per-file interval to global bytes
        file_l_global = offset + file_l
        file_r_global = offset + file_r
        if file_r_global < total_l or file_l_global > total_r:
            continue
        ans.add(p)
    offset += size

for p in sorted(ans):
    print(p)
```该解决方案小心地使用整数运算来避免浮点错误。`(p * size + 99) // 100`是一种安全的实施方式`ceil(p * size / 100)`。 将每个文件的间隔移动`offset`将它们与总进度条对齐。 间隔重叠检查确保我们只添加可以同时发生的百分比。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n * 101) | 我们迭代每个文件和每个可能的百分比 (0-100)。 最大 n=100。 |
 | 空间| 奥(101) | 我们存储百分比集，最多 101 个整数。 |

 给定 n ≤ 100，该算法最多执行 10100 次迭代，这对于现代 CPU 来说是微不足道的。 大文件大小不会影响性能，因为不需要每字节模拟。
