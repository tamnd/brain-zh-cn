 ## 解决方案
 ## 问题理解

 我们得到了多组“事件”，其中每个事件最初属于特定的一天。 该数组已排序，每个值都告诉我们提交发生在哪一天。 

每次提交都是灵活的：我们可以将其保留在原来的日期或向前推进一天。 不允许其他移动，并且每个提交都是独立移动的。 

选择每个提交的去向后，我们会查看提交的跨天提交分布。 如果一天至少有一次提交，则该天被视为“活跃”。 我们的目标是尽可能延长连续的活跃天数。 

因此，问题不在于最大化全局活跃天数，而在于形成一个最长的不间断块，其中每天至少有一个分配的提交。 

约束很小：每个测试最多 50 次提交，值最多 100。这立即告诉我们，每个测试 O(n^3) 甚至 O(n^4) 左右的任何解决方案都可以，但我们仍然应该以更清晰的组合或贪婪构造为目标，而不是强制所有分配。 最多有 100 个测试，因此每个测试解决方案的 O(n^2) 或 O(n^3) 是安全目标。 

一个微妙的困难来自于提交交互的事实：向前推进一个提交可能会与另一天发生冲突，或者可能有助于填补空白。 独立处理日子的天真贪婪可能会失败。 

暴露天真的想法的一种边缘情况是所有提交都集中在一天内，例如`[10, 10, 10]`。 您可能认为答案始终是 1，因为所有内容都从一个地方开始，但将一些内容移到第二天会创建一个长度为 2 的连续块。 

另一个棘手的情况是当存在间隙时，例如`[1, 3, 5]`。 +1 转变的能力可以填补一些空白，但不一定是全部，并且必须协调决策。 

## 方法

 一个蛮力的想法是将每个提交视为有两个选择：留在一天`a[i]`或移至`a[i] + 1`。 这给出了`2^n`作业。 对于每个分配，我们构建一个多天的频率图，然后计算所有天都非空的最长连续段。 

这是正确的，因为它枚举了所有可能的有效配置，但速度太慢。 和`n = 50`，我们得到关于`2^50`的可能性，这是完全不可行的。 

关键的观察是我们实际上并不关心个人作业。 我们只关心能否把每一天都覆盖在某个区间内。 这将问题转化为覆盖构建问题而不是子集枚举问题。 

我们可以考虑每天边界周围“可用”的提交数量，而不是独立地决定每个提交。 由于每次提交仅跨越相邻的两天，因此它的行为就像一个小间隔`[a[i], a[i]+1]`。 我们想要选择放置位置，以便覆盖整个整数点区间。 

重新解释问题的一个有用方法是考虑“流动”提交来填补空白。 如果有一天缺少提交，我们会尝试借用前几天仍然可以向前移动的提交。 

这导致对可能的起点进行贪婪扫描：我们尝试从每天开始构建最长的有效段，并模拟我们是否可以使用可用的提交来继续填充第二天。 

因为每次提交只能移动一步，所以结构是本地的，我们只需要跟踪可以向前推进多少“剩余”提交。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（所有作业）| O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 贪婪模拟几天 | O(n^2) | O(n^2) | O(n) | 已接受 |

 ## 算法演练

 我们将单独对待每个测试。 

1.构建频率数组`cnt[d]`代表当天最初发生的提交数量`d`。 自从`a_i ≤ 100`，我们可以安全地压缩到一个最多 101 或 102 的数组中。 
2. 对于每个可能的开始日`L`，我们尝试构造最长的有效段`[L, R]`。 
3.我们维护一个变量`carry`，它代表有多少提交可以转移到第二天。 最初`carry = 0`。 
4. 我们每天迭代`L`向上。 在每一天`d`，我们添加`cnt[d]`进入`carry`，因为从当天开始提交`d`可以留下来或搬到`d+1`。 
5、一定要保证日`d`已满。 如果`carry == 0`，那么日`d`无法激活，我们停止扩展此段。 
6. 如果`carry > 0`，我们“使用”一次提交来覆盖这一天`d`，所以我们递减`carry`1. 剩余的`carry`继续前进可能会填补未来的日子。 
7. 我们不断延伸，直到无法覆盖一天为止，并跟踪所有起点的最大长度。 

直觉是每天消耗一次提交，同时还收集当天的新提交。 由于每次提交只能移动一步，因此它的行为就像在一天进入的供应单位`a[i]`并可用于`a[i]`或者`a[i]+1`。 

### 为什么它有效

 关键的不变量是`carry`始终表示尚未分配给某一天但仍可在当前或第二天使用的提交数。 每一次提交最多使用一次，并且只能延迟一步，因此最多可以向前推进一次。 

在每一天，如果我们无法支付一次提交的“成本”，那么任何分配都无法使这一天变得活跃，因为所有可能到达这一点的可用提交都已经用尽。 相反，如果我们有能力支付，使用一台设备总是安全的，因为延迟使用只会增加未来几天的灵活性。 

这种贪心模拟只要继续下去就会隐式构造一个有效的赋值，因此它产生的任何段都是可行的，并且由于我们尝试所有的开始，因此找到了最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        if n == 0:
            print(0)
            continue

        max_day = max(a) + 2
        cnt = [0] * (max_day + 5)

        for x in a:
            cnt[x] += 1

        ans = 0

        for L in range(1, max_day + 1):
            carry = 0
            length = 0

            for d in range(L, max_day + 1):
                carry += cnt[d]

                if carry == 0:
                    break

                carry -= 1
                length += 1

            ans = max(ans, length)

        print(ans)

if __name__ == "__main__":
    solve()
```实现直接遵循贪心构造。 频率数组存储每天发起的提交数量。 

对于每个开始日`L`，我们重置`carry`因为每个部分都是独立的。 然后，我们模拟向前：每天添加可用提交并花费一个来保持当天的活动状态。 一旦我们无法花费一分钱，该部分就结束了。 

迭代次数的选择`max_day + 1`确保我们考虑到从最后一天转移的提交。

 ## 边缘情况

 当所有提交都发生在同一天时，算法正确地允许使用移位提交扩展到第二天。 套利在起始点累积，并允许额外一天，但不能再多了，因为之后没有新的供应到达。 

当提交量严格增加 1 时，每天恰好供应一个单位，因此套利保持稳定，并且该部分自然会扩展到所有日期。 该算法通过绝不让进位降至零来反映这一点。 

当存在间隙时，例如`[1, 3, 5]`，除非较早积累了足够的利差，否则模拟无法跨越缺失的天数。 中断条件恰好在第一个不可避免的空闲日触发，这与没有任何分配可以在那里产生覆盖的事实相匹配。
