 ## 解决方案
 ## 问题理解

 一群朋友想要使用三种资源制作相同的吐司：软饮料、酸橙片和盐。 每个 Toast 都会消耗固定数量的每种资源。 任务是确定在至少一个资源耗尽之前每个朋友可以完成多少次祝酒。 

输入给出了朋友的数量、饮料瓶的数量和大小、酸橙和每个酸橙切片的数量、盐的量以及一个吐司所需的每种成分的量。 根据这些值，我们必须计算每个资源可以独立生成多少个 Toast，然后确定限制资源。 

约束很小，每个值最多为 1000。即使是低效的解决方案也可以在限制内轻松运行。 不需要先进的算法、数据结构或优化技巧。 挑战只是将措辞翻译成正确的算术。 

最常见的错误是误解最终答案所代表的含义。 我们没有被要求提供祝酒的总数。 我们被问到每个朋友可以平等地祝酒多少次。 

考虑这个输入：```
3 1 3 1 1 100 3 1
```该饮料仅允许`1 * 3 / 3 = 1`总吐司。 粗心的解决方案可能会打印出来`1`，但这是整个组的祝酒总数。 由于有 3 个朋友，每个朋友都可以`1 / 3 = 0`干杯。 正确的输出是：```
0
```另一个微妙的情况是当一种资源比其他资源小得多时。```
5 100 100 1 1 1 1 1
```饮料和酸橙很丰富，但盐只够一份吐司。 分配给 5 个朋友可以得到`0`。 忘记在所有资源中取最小值的解决方案将在这里失败。 

整数除法也是必不可少的。 祝酒必须完整。 不允许分段敬酒。```
2 1 5 1 1 100 6 1
```饮料只有5毫升，每个吐司需要6毫升。 正确的饮酒祝酒次数是`0`， 不是`0.833...`。 

## 方法

 一种蛮力方法可以模拟一次制作一个吐司。 每一步都会减去所需的饮料、一片柠檬片和所需的盐，直到某些资源变得不足。 最后，我们将成功祝酒的次数除以朋友的数量。 

这是有效的，因为每个 toast 都会消耗固定数量的资源。 模拟很容易推理并且总是正确的。 即使在最坏的情况下，可能的祝酒次数也足够小，可以在时间限制内轻松完成。 

Still, simulation is unnecessary. 问题的结构给出了直接的数学捷径。 

每个资源独立地确定总 Toast 的最大数量：

 该饮料提供：```
(k * l) / nl
```总吐司。 

酸橙提供：```
(c * d)
```总共吐司，因为每个吐司只需要一片。 

盐提供：```
p / np
```总吐司。 

实际的Toast总数是这三个值中的最小值，因为第一个耗尽的资源停止了生产。 由于每个朋友都必须收到相同数量的祝酒词，因此我们将总数平均分配给`n`朋友们。 

这将问题简化为一些算术运算和整数除法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(T)| O(1) | O(1) | 已接受 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 这里，`T`是模拟吐司的数量。 

## 算法演练

 1. 从输入中读取八个整数。 
2. 计算可用饮料总量。```
total_drink = k * l
```这会将瓶子数量转换为总毫升数。 

1. 计算该饮料总共可以支持多少次吐司。```
drink_toasts = total_drink // nl
```需要整数除法，因为部分 toast 无效。 

1. 计算石灰片的总数。```
lime_toasts = c * d
```每个吐司只消耗一片，因此该值已经等于酸橙可能的吐司数量。 

1. 计算盐总共可以支持多少次吐司。```
salt_toasts = p // np
```同样，整数除法消除了不完整的吐司。 

1. 找出三个吐司数中最小的一个。```
total_toasts = min(drink_toasts, lime_toasts, salt_toasts)
```限制资源决定了Toast 的最大可能数量。 

1. 平分给所有朋友。```
answer = total_toasts // n
```1. 打印结果。 

### 为什么它有效

 每个吐司都会消耗固定量的饮料、酸橙和盐。 这意味着每个资源独立地对总 Toast 数量施加上限。 任何超出这些界限之一的尝试都将需要比现有资源更多的资源。 

取三个界限中的最小值给出总的吐司的最大可行数量。 除以朋友数量即可得到每个朋友的最大相等吐司数量。 由于所有计算都使用整数除法，因此该算法永远不会计算不完整的 toast。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k, l, c, d, p, nl, np = map(int, input().split())

drink_toasts = (k * l) // nl
lime_toasts = c * d
salt_toasts = p // np

total_toasts = min(drink_toasts, lime_toasts, salt_toasts)

print(total_toasts // n)
```第一行在一条语句中读取所有八个整数。 由于该问题只有一个测试用例，因此不存在循环。 

饮料计算方法是将瓶子数量乘以每瓶的毫升数，然后再除以每个吐司所需的量。 颠倒这个顺序是不正确的，因为整数除法会过早丢失信息。 

酸橙的计算更简单，因为每个吐司只需要一片。 不需要划分。 

盐计算使用整数除法，原因与饮料计算相同，不允许不完整的祝酒。 

这`min`调用是关键步骤。 即使两个资源可以支持多个 Toast，最小的资源也会成为瓶颈。 

最后，再次用整数除法将答案平均分配给所有朋友。 这避免了给人们分配分数祝酒词。

## 测试用例```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n, k, l, c, d, p, nl, np = map(int, input().split())

    drink_toasts = (k * l) // nl
    lime_toasts = c * d
    salt_toasts = p // np

    total_toasts = min(drink_toasts, lime_toasts, salt_toasts)

    print(total_toasts // n)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("3 4 5 10 8 100 3 1\n") == "2\n", "sample 1"

# minimum values
assert run("1 1 1 1 1 1 1 1\n") == "1\n", "minimum case"

# not enough drink for one toast per friend
assert run("3 1 3 1 1 100 3 1\n") == "0\n", "group division case"

# salt is the bottleneck
assert run("5 100 100 100 100 4 1 2\n") == "0\n", "salt bottleneck"

# maximum values
assert run("1000 1000 1000 1000 1000 1000 1 1\n") == "1000\n", "maximum values"

print("All tests passed.")

 ## 边缘情况

 一个容易犯的错误就是忘记了所有朋友的答案都必须是平等的。 

考虑：```
3 1 3 1 1 100 3 1
```该算法计算：```
drink_toasts = (1 * 3) // 3 = 1
lime_toasts = 1
salt_toasts = 100
```最小值是`1`，这意味着一组人总共可以做一个祝酒词。 平均分配给 3 个朋友得出：```
1 // 3 = 0
```所以正确答案是：```
0
```当一种资源远远小于其他资源时，就会出现另一种棘手的情况。```
5 100 100 1 1 1 1 1
```该算法计算：```
drink_toasts = 10000
lime_toasts = 1
salt_toasts = 1
```最小值是`1`，所以尽管喝了很多酒，敬酒的总数却只有一次。 

分配给 5 个朋友后：```
1 // 5 = 0
```该算法正确识别了瓶颈资源。 

整数除法也很关键。```
2 1 5 1 1 100 6 1
```饮料计算变为：```
(1 * 5) // 6 = 0
```尽管5毫升接近所需的6毫升，但对于完整的吐司来说仍然不够。 因为该算法使用楼层划分，所以它正确地拒绝部分 toast 并输出：```
0
```
