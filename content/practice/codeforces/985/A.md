 ## 解决方案
 ## 问题理解

 我们给定一条长度的线$n$， 在哪里$n$是偶数，并且每个位置要么是空的，要么恰好包含一个棋子。 棋盘以交替图案着色，从位置 1 开始为黑色，因此位置看起来像 B、W、B、W 等。 

必须移动所有棋子，以便最终它们仅占据单一颜色的单元格，或者全部是黑色单元格，或者全部是白色单元格。 移动包括将一个棋子向左或向右移动一步到一个空单元格中，并且棋子不能重叠或离开棋盘。 

目标是最大限度地减少实现所有棋子仅位于一种选定颜色的单元格上的配置所需的此类单步移动的总数。 

输入尺寸较小，$n \le 100$，因此即使是二次或三次解也很容易足够快。 这意味着我们可以直接为每个候选目标配置模拟运动或计算成本，而不必担心由于性能原因而强制使用前缀预处理或贪婪启发式等优化技巧。 

一个微妙的边缘情况是由于我们不知道哪种颜色是最佳的这一事实。 幼稚的方法可能会假设黑色或白色而不检查两者，这可能会失败。 例如，如果碎片大部分与白色单元对齐，但稍微靠近黑色单元，则错误的假设会导致更高的总成本。 

另一个陷阱是试图一步一步地模拟运动。 由于各个部件在移动过程中会相互阻挡，因此简单的模拟可能会错误地估计成本，因为如果处理不当，中间状态很重要。 正确的解决方案完全避免模拟并与直接位置成本推理一起使用。 

## 方法

 强力解释是模拟所有可能的移动序列，直到所有棋子落在任一颜色的有效目标单元上。 这将涉及探索将碎片分配给目标单元的所有方法，然后在碰撞约束下模拟最短的移动序列。 即使与$k$件，仅作业数量就是$O(k!)$，并且每次模拟至少需要线性时间来解决碰撞。 即使对于中等程度的人来说，这也很快变得不可行$k$。 

关键的简化是要注意，如果我们确定它们的最终目的地，这些部分不会以改变总成本的方式相互作用。 由于每次移动只是将一个棋子移动一个位置到一个空槽中，并且我们只关心最终占用的位置，因此问题简化为将每个棋子分配给所选颜色的目标单元格并计算距离总和。 

一旦我们确定了一种颜色，比如黑色，我们就会提取板上的所有黑色位置。 那么问题就变成了将当前棋子位置与这些单元格的子集相匹配。 通过对两个列表进行排序并按顺序配对来实现最佳分配。 这是有效的，因为在一维线中，匹配的绝对差值的最小和总是通过排序配对获得的。 

我们计算黑色单元的成本，并再次计算白色单元的成本，然后取最小值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（模拟所有动作）| 指数| O(k!) | 太慢了|
 | 最佳（排序和配对）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 ### 最优策略

 1. 将所有棋子的位置提取到一个列表中。 
2. 建立两个目标列表：一个包含所有黑色位置，另一个包含所有白色位置。 
3. 对于每个目标列表，计算将片段与目标匹配的成本。 
4. 要计算匹配成本，请对棋子位置和目标位置进行排序。 
5. 按排序顺序对元素进行配对并对绝对差求和。 
6. 取两个计算成本中的最小值并输出。 

配对步骤的关键思想是排序确保大位置与大位置匹配，小位置与小位置匹配，防止交叉分配导致不必要的长跳转。 

### 为什么它有效

 正确性依赖于一条线上最佳分配的标准属性：两个大小相等的集合之间的绝对差的最小和是通过对两者进行排序并按顺序匹配来实现的。 任何交叉分配都可以通过交换端点来改进，这会严格减少或保留总距离。 由于两种颜色选择都减少了这个匹配问题，因此评估两者并采取最小值保证了全局最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
pieces = list(map(int, input().split()))

# build black and white positions (1-indexed board)
black = []
white = []

for i in range(1, n + 1):
    if i % 2 == 1:
        black.append(i)
    else:
        white.append(i)

def cost(targets):
    if len(targets) != len(pieces):
        return float('inf')
    pieces_sorted = sorted(pieces)
    targets_sorted = sorted(targets)
    return sum(abs(p - t) for p, t in zip(pieces_sorted, targets_sorted))

print(min(cost(black), cost(white)))
```该实现首先收集所有棋子位置。 然后，它根据棋盘颜色构建两个可能的目标集。 辅助函数使用排序配对来计算匹配成本。 

一个微妙的点是确保计数匹配：只有一种颜色完全匹配$n/2$单元格，但块数保证与两个颜色类之一匹配，因此我们通过返回无穷大来保护另一种情况。 

## 工作示例

 ### 示例 1

 输入：```
6
1 2 6
```黑色位置：[1,3,5]

 白色位置：[2,4,6]

 #### 搭配黑色

 | 步骤| 已排序 | 目标已排序 | 配对 | 成本|
 | --- | --- | --- | --- | --- |
 | 1 | [1,2,6]| [1,3,5]| (1,1),(2,3),(6,5) | 0 + 1 + 1 = 2 |

 #### 与白色搭配

 | 步骤| 已排序 | 目标已排序 | 配对 | 成本|
 | --- | --- | --- | --- | --- |
 | 1 | [1,2,6]| [2,4,6]| (1,2),(2,4),(6,6) | 1 + 2 + 0 = 3 |

 最小值为 2。 

这证实了评估两种颜色选择是必要的，因为从初始位置来看，更好的选择并不总是显而易见的。 

### 示例 2

 输入：```
4
1 3
```黑色位置：[1, 3]

 白色位置：[2, 4]

 #### 搭配黑色

 | 步骤| 已排序 | 目标已排序 | 配对 | 成本|
 | --- | --- | --- | --- | --- |
 | 1 | [1,3]| [1,3]| (1,1),(3,3) | (1,1),(3,3) | 0 |

 #### 与白色搭配

 | 步骤| 已排序 | 目标已排序 | 配对 | 成本|
 | --- | --- | --- | --- | --- |
 | 1 | [1,3]| [2,4]| (1,2),(3,4) | 1 + 1 = 2 |

 最小值为 0。 

这表明，即使两种配置都有效，其中一种配置已经可以在不进行任何移动的情况下达到最佳状态。

## 测试用例```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    n = int(input())
    pieces = list(map(int, input().split()))

    black, white = [], []
    for i in range(1, n + 1):
        if i % 2:
            black.append(i)
        else:
            white.append(i)

    def cost(targets):
        if len(targets) != len(pieces):
            return float('inf')
        a = sorted(pieces)
        b = sorted(targets)
        return sum(abs(x - y) for x, y in zip(a, b))

    print(min(cost(black), cost(white)))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdout = old_stdout
    return out.strip()

# provided sample
assert run("6\n1 2 6\n") == "2"

# minimum input
assert run("2\n1\n") == "0"

# already optimal on black
assert run("4\n1 3\n") == "0"

# needs movement
assert run("4\n1 2\n") == "1"

# worst spread
assert run("6\n1 6\n") in ["2", "2"]

# symmetric case
assert run("8\n1 3 5 7\n") == "0"

 | 4, 1 2 | 1 | 单动调节|

 ## 边缘情况

 关键的边缘情况是所有部件都已采用一种颜色。 对于输入：```
4
1 3
```黑色的单元格正是被占用的单元格。 该算法计算零成本，因为排序配对匹配相同的位置。 

另一个极端情况是碎片集中在错误的奇偶校验上。 为了：```
4
2 4
```黑色目标是[1,3]。 排序给出配对 (2,1),(4,3)，导致成本 2。白色目标是 [2,4]，成本为 0。该算法正确选择白色配置，因为它对称地评估两种可能性，并且不假设奇偶校验对齐。 

第三种边缘情况是初始间距不均匀。 即使碎片相距很远，基于排序的匹配也确保不会交叉分配人为地增加成本，因为每个碎片都按顺序与其最近的结构目标配对，而不是贪婪地选择局部最接近的位置。
