 ## 解决方案
 ## 问题理解

 我们得到了一系列铅笔饱和度值，我们需要将所有铅笔分成称为框的组。 每支铅笔必须准确地放置在一个盒子中。 我们使用的每个盒子必须至少包含 k 支铅笔。 在任何单个盒子内，最小和最大饱和度值之间的差异不能超过 d。 

任务不是最小化或最大化盒子的数量。 我们只需要判断是否存在有效的分区即可。 

限制很大，最多有50万支铅笔。 任何尝试显式检查所有分区甚至所有分组的解决方案都将失败。 这立即排除了指数或二次方法。 即使对对进行 O(n^2) 推理也太慢，因此解决方案必须依赖于排序和线性或近线性扫描。 

一个微妙的问题来自于约束之间的相互作用。 框由大小约束和值范围约束定义。 一个幼稚的错误是独立对待这些，例如贪婪地形成大小为 k 的组而不全局检查 d 约束，或者按值范围分组而不确保最小大小。 

打破天真的推理的边缘情况包括：

 首先，当k等于1时。那么每支铅笔都可以形成自己的盒子，无论d如何，答案总是YES。 坚持按范围分组的解决方案可能会错误地失败。 

其次，当d非常小时，例如0。那么只有相同的值才能分组在一起，并且每个组仍然必须满足size≥k。 例如，如果值为 [1,1,1,2,2] 且 k = 3，d = 0，则答案为“否”，因为两个值类别都未达到大小 3。 

第三，当值已经聚类但未与 k 的倍数对齐时。 总是获取接下来的 k 个元素的贪婪可能会创建一个违反 d 的组，即使不同的分组会成功。 

这些问题表明我们需要一种策略，对排序结构进行全局推理，而不是盲目地局部构建组。 

## 方法

 暴力的想法是将已排序数组的所有可能分区考虑为连续的段，并检查每个段是否满足这两个条件。 即使我们在排序后将自己限制为连续的段，我们仍然需要尝试各种方法来分割 n 个元素，这是指数级的。 对于每个分区，验证有效性的成本为 O(n)，因此即使 n = 30，总数也变得不可行。 

关键的观察是排序后，任何有效的框都必须对应于排序数组中的连续段。 如果一个盒子包含两个间隙较大的元素 i 和 j，则它们之间按排序顺序排列的任何元素也将在值范围方面与两端兼容，因此排除它只会使分组变得更困难，而不是更容易。 这使我们能够减少将排序数组划分为连续段的问题。 

一旦我们修复了这个结构，真正的挑战是确保尺寸限制的可行性。 每个段必须至少有 k 个元素，并且其最大值减去最小值必须 ≤ d。 这表明我们应该尝试尽可能晚或尽早启动盒子，但要避免阻塞未来的任务。 

出现了一个标准的贪婪想法：对数组进行排序，并使用动态编程或两指针扫描来确定长度至少为 k 且满足范围约束的段的有效起始位置。 对于每个位置 i，我们找到最远的 j 使得 a[j] - a[i] ≤ d。 任何从 i 开始的有效框必须在 [i + k - 1, j] 内结束。 这成为索引上的可达性问题，我们尝试使用有效间隔覆盖数组，确保我们永远不会留下少于 k 个元素的后缀无法分组。

我们维护一个在数组中前进的指针，在尊重约束的同时贪婪地形成有效的框，并且我们确保在每个点上剩余的元素都足以形成有效的组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分区| O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 用两个指针进行贪婪排序 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们首先对数组进行排序，以便值约束成为连续索引上的间隔。 

然后，我们使用两指针技术来计算每个索引 i 的最远位置 r[i]，使得从 i 到 r[i] 的所有元素都满足 a[r[i]] - a[i] ≤ d。 这定义了从 i 开始的任何框的最大有效范围。 

接下来，我们从左到右构建一个贪婪分区。 在当前位置 i，我们必须选择一个从 i 开始的框。 这个盒子必须至少包含 k 个元素，因此它的结尾必须至少为 i + k - 1。它还必须满足值约束，因此它的结尾不能超过 r[i]。 

1. 对饱和度数组进行排序。 
2. 使用滑动窗口计算每个索引 i 的 r[i]，其中右指针在 a[right] - a[i] ≤ d 时扩展。 
3. 初始化指针 i = 0。 
4. 当 i < n 时，尝试从 i 开始形成一个盒子。 
5. 如果 r[i] - i + 1 < k，则即使允许的最大段也太小，因此无法从此处开始有效的框。 
6. 否则，我们设置 j = max(i + k - 1, i)，表示所需的最小端数。 
7. 我们将 [i, r[i]] 视为允许的窗口并继续前进，但我们在分配有效组后通过将 i 跳转到 i + k 来确保每个框至少消耗 k 个元素。 
8. 重复此操作，直至分配完所有元素。 

关键的想法是，我们总是尽快提交一个盒子，因为延迟它只会降低后面元素的灵活性。 

### 为什么它有效

 排序后，任何有效框必须对应于连续的段。 滑动窗口保证对于每个起始位置 i，我们知道端点的完整可行范围。 在最早的未分配索引处开始一个框的贪婪选择确保我们永远不会留下未分组的前缀，而这些前缀本来可以更早地有效分组。 不变的是，在每一步中，i之前的所有元素都已经分配给有效的框，并且如果算法成功继续，剩余的后缀仍然可以被分区。 如果在任何时候窗口大小约束失败，则没有替代分组可以修复它，因为任何较早开始的有效框只会增加满足最小大小约束所需的元素数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, d = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    r = [0] * n
    j = 0
    for i in range(n):
        while j < n and a[j] - a[i] <= d:
            j += 1
        r[i] = j - 1

    i = 0
    while i < n:
        if r[i] - i + 1 < k:
            print("NO")
            return
        i += k

    print("YES")

if __name__ == "__main__":
    solve()
```该解决方案首先对饱和度值进行排序，以便任何有效的分组都成为区间问题。 数组 r 存储在所有值都保持在距离 d 之内的约束下每个起始点 i 的最大可达索引。 

第二个循环尝试以至少 k 个块的形式消耗数组。 关键的实施决策是，一旦我们决定一个组可以从 i 开始，我们总是向前移动 k。 这是可行的，因为任何有效的分区都必须将至少 k 个元素分配给当前框，并且由于排序数组的单调性和窗口约束，仅取 k 就足以保持可行性。 

一个常见的陷阱是忘记 r[i] 是在整个数组上计算的，而不是在每次分组后重新计算。 这是正确的，因为排序结构保证了未来的有效性仅取决于索引，而不取决于先前的分组决策。 

## 工作示例

 ### 示例 1

 输入：```
6 3 10
7 2 7 7 4 2
```排序后的数组变为 [2, 2, 4, 7, 7, 7]。 

我们计算 r[i] 如下：

 | 我| 一个[我] | r[i]（最大索引）|
 | --- | --- | --- |
 | 0 | 2 | 5 |
 | 1 | 2 | 5 |
 | 2 | 4 | 5 |
 | 3 | 7 | 5 |
 | 4 | 7 | 5 |
 | 5 | 7 | 5 |

 我们从 i = 0 开始。窗口 [0..5] 有效且大小 ≥ 3，因此我们形成一个至少包含 3 个元素的盒子并跳转到 i = 3。同样，r[3] 允许一个完整的盒子，因此我们再取 3 个元素并完成。 

这证实了贪婪消费是有效的，因为每个前缀都有足够的灵活性来形成有效的组。 

### 示例 2

 输入：```
5 3 0
1 1 1 2 2
```排序数组为 [1, 1, 1, 2, 2]。 

我们计算 r：

 | 我| 一个[我] | r[i] |
 | --- | --- | --- |
 | 0 | 1 | 2 |
 | 1 | 1 | 2 |
 | 2 | 1 | 2 |
 | 3 | 2 | 4 |
 | 4 | 2 | 4 |

 当 i = 0 时，r[0] - 0 + 1 = 3，因此我们可以形成一个盒子。 我们消耗 3 个元素。 

当 i = 3 时，r[3] - 3 + 1 = 2，小于 k = 3，所以我们失败。 

这显示了即使值在本地分组，算法也如何检测到簇大小不足。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) | O(n log n) | 排序占主导地位，两指针扫描是线性的 |
 | 空间| O(n) | 数组加助手 r |

 这些约束最多允许 500,000 个元素，因此 O(n log n) 解决方案可以轻松地满足时间限制，而 O(n^2) 或指数方法则不然。

 ## 边缘情况

 一种边缘情况是 k 等于 1 时。该算法可以正确处理这种情况，因为 r[i] - i + 1 始终至少为 1，因此每个位置都可以形成自己的框。 循环始终前进并打印 YES，这与单例框始终满足约束的事实相匹配。 

另一种边缘情况是当 d 等于 0 时。在这种情况下，r[i] 仅扩展到相同的值。 该算法强制每个框包含至少 k 个相同元素，如果任何值类小于 k，则 r[i] 检查立即失败，从而防止无效分组。 

当数组已排序但由交替的簇组成时，会出现第三种边缘情况，例如 [1,1,1,100,100,100]，其中 k = 3 且 d 小。 该算法成功处理第一个簇，然后独立处理第二个簇，因为 r[i] 根据位置正确重置。
