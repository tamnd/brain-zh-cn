 ## 解决方案
 ## 问题理解

 我们得到一个网格，其中一些单元格已经包含`'X'`其余单元格包含`'.'`。 

最初的故事描述了闪电摧毁向日葵的故事。 从图的角度来看，标记的单元格`'X'`是已经选定的顶点。 我们被允许改变任何`'.'`进入`'X'`，但我们永远不被允许改变现有的`'X'`回到`'.'`。 

最后一组`'X'`单元必须在 4 向邻接下形成连通的非循环图。 在图术语中，所有的归纳图`'X'`细胞必须是一棵树。 

一个重要的信息是初始的特殊结构`'X'`细胞。 它们中的任何两个都不相邻，即使是对角线也是如此。 现存的`'X'`单元通过至少一行和一列彼此隔离。 

所有网格大小的总和最多为 250,000。 这立即表明任何可接受的解决方案都应该只处理每个细胞恒定的次数。 一个$O(nm)$或者$O(nm \log(nm))$解决方案很容易足够快，而任何涉及在整个网格上重复图形搜索的事情都将变得不必要。 

困难的部分不是连接性。 由于我们可以自由添加新的`'X'`细胞，连接一切都很容易。 挑战在于避免循环，同时保证每个原创`'X'`保留在最后一棵树中。 

一些边缘情况很容易被错误处理。 

考虑一个单行网格：```
1 10
....X.X.X.
```没有空间构建垂直连接器。 任何假设三行块的构造都会失败。 接受的解决方案自然必须减少到填充整行。 

考虑一个高度不能被三整除的网格：```
5 5
.....
.....
.....
.....
.....
```仅在第 1、4、7 行上构建的模式会使最后两行断开连接。 该构造必须显式处理最后一或两行。 

另一个微妙的情况是：```
4 4
....
.X.X
....
.X.X
```原来的`'X'`单元格位于不同的列中。 如果我们每次都使用固定列连接行块，一些现有的`'X'`细胞最终可能会与主要结构分离。 必须根据现有的情况选择连接器列`'X'`细胞已经出现。 

## 方法

 暴力的观点是将每个单元视为图顶点并搜索包含所有原始单元格的任何树`'X'`细胞。 人们可以想象在每次选择后逐渐添加单元并检查连通性和非循环性。 

这样的搜索在理论上是正确的，因为有效的答案总是存在的。 不幸的是，国家空间是巨大的。 一个$500 \times 500$网格包含 250,000 个单元，因此即使独立地决定每个单元是否属于最终的树也是完全不可行的。 

关键的观察来自于对原始内容的不寻常限制`'X'`细胞。 由于没有两个原件`'X'`细胞接触时，它们还不能创造循环。 我们只需要一种系统的方式来连接它们。 

公认的结构建立了骨干。 每第三行都完全充满`'X'`。 这些行成为跨越整个网格宽度的水平高速公路。 

一旦存在这样的高速公路，连续的高速公路之间只需要一个垂直连接器。 两条高速公路之间的行最多包含两行。 因为原创`'X'`细胞被分离，任何`'X'`出现在这些中间行中的元素可以附加到选定的连接器列，而无需创建循环。 

这会产生一个树状结构。 填充的行形成主骨架，而中间行中的单元格悬挂在该骨架上。 

整个结构是确定性的，并且仅接触每个单元恒定的次数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力搜索 | 指数| 指数| 太慢了|
 | 建设性模式| O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 首先假设$m > 1$。 

1. 将每第三行完全填满`'X'`。 使用基于 0 的索引，这些是行 0、3、6、9 等。 
2. 考虑每对连续的填充行。 它们之间有一或两排中间行。 
3. 在这些中间行中搜索现有的`'X'`。 
4. 如果现有`'X'`找到后，选择其列作为连接器列。 
5. 如果没有现有的`'X'`存在于中间行中，选择第 0 列。 
6. 在连接器列中填充`'X'`遍历当前块的所有行。 这会将两个相邻的高速公路行连接成一个连接的组件。 
7. 处理完所有完整的三行块后，处理底部仅保留两行的特殊情况。 
8. 对于最后两行，填充两行中已包含的每一列`'X'`。 这会将剩余的行合并到上面的结构中。 

什么时候$m = 1$，结构是镜像的。 每个细胞都充满了`'X'`。 单列不能包含循环，因此结果自动为一棵树。 

### 为什么它有效

 每第三行都被完全填满，形成长长的水平路径。 连续的公路行仅由一座垂直桥梁连接。 由于相邻公路行之间只有一座桥，因此它们之间不能形成环路。 

任意原件`'X'`位于中间行的部分会附着在该桥柱上。 由于原始单元相互不接触，因此将它们连接到单个骨干网无法创建替代路由。 

生成的结构类似于一棵树，其树干由完全填充的行组成，其分支是从输入继承的单元格。 每一个`'X'`属于一个连接的组件，并且主要组件之间的每个连接都使用唯一的桥。 没有替代路径的连通图是一棵树，因此满足要求。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        g = [list(input().strip()) for _ in range(n)]

        if m == 1:
            for i in range(n):
                g[i][0] = 'X'
            out.extend(''.join(row) for row in g)
            continue

        for r in range(0, n, 3):
            for c in range(m):
                g[r][c] = 'X'

        r = 0
        while r + 3 < n:
            col = -1

            for c in range(m):
                if g[r + 1][c] == 'X' or g[r + 2][c] == 'X':
                    col = c
                    break

            if col == -1:
                col = 0

            g[r + 1][col] = 'X'
            g[r + 2][col] = 'X'

            r += 3

        if n % 3 == 2:
            last = n - 1
            prev = n - 2

            for c in range(m):
                if g[prev][c] == 'X' or g[last][c] == 'X':
                    g[prev][c] = 'X'
                    g[last][c] = 'X'

        out.extend(''.join(row) for row in g)

    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```第一个分支处理特殊情况$m=1$。 单列只能形成一条路径，因此填充每个单元格就足够了。 

下一个循环填充行`0, 3, 6, ...`完全地。 这是建设的支柱。 

这`while`循环一次处理一个三行块。 寻找`col`寻找任何已经存在的`'X'`在中间两行。 选择这样的柱可以保证现有细胞自然附着在主干上，而不是被隔离。 

决赛`n % 3 == 2`调整是最常见的错误来源。 如果没有它，底部两行可能会与结构的其余部分保持断开连接。 该代码合并包含以下内容的所有列`'X'`在任一行中。 

不需要递归、图遍历或循环检测，因为构造本身保证了所需的结构。

 ## 边缘情况

 考虑：```
1 10
....X.X.X.
```宽度很大，但高度却是一。 算法输入`m > 1`分支并完全填充第 0 行。 由于没有其他行，因此不会进行连接器处理。 输出变为：```
XXXXXXXXXX
```这是一条简单的路径。 

考虑：```
5 5
.....
.....
.....
.....
.....
```第 0 行和第 3 行成为高速公路。 没有现有的`'X'`第 1 行和第 2 行中的单元格，因此选择第 0 列作为连接器。 由于两行保留在底部，因此最终的合并规则将处理它们。 不能出现断开区域。 

考虑：```
4 4
....
.X.X
....
.X.X
```填充第 0 行和第 3 行后，算法将检查第 1 行和第 2 行。它会找到现有的`'X'`在第 1 列中并使用该列作为桥梁。 原始细胞直接附着在主干上，而不是留在单独的分支中。 

这些情况正是临时构建往往会失败的地方。 公认的模式是专门设计的，使它们都可以使用相同的简单规则集。
