 ## 解决方案
 ## 问题理解

 我们得到了排列在一系列位置上的排列。 两名玩家控制两个标记，一个从青山选择的索引开始，另一个由丹尼尔看到第一个选择后选择。 然后，他们轮流沿着相邻位置移动这些标记，但每次移动都受到排列值的限制：青山的标记必须始终移动到具有严格较小值的相邻位置，而丹尼尔的标记必须始终移动到具有严格较大值的相邻位置。 此外，两个标记都不允许移动到另一个标记的当前位置。 

当玩家轮到没有合法动作时，游戏结束，该玩家输。 任务是计算假设两名球员都发挥最佳状态，青山标记的首发位置有多少可以保证获胜。 

输入大小最多允许 100,000 个元素，这会立即排除任何针对每对起始位置模拟游戏的解决方案。 尝试评估每对可能的起始位置的结果的简单方法将需要二次或更差的工作，这在 1 秒限制下是不可行的。 我们的目标应该是接近线性或线性时间。 

问题的一个微妙方面是，两个参与者都受到沿值而不是指数的单调运动的限制。 这会在排列上创建定向“流”，其行为类似于有向图，仅在相邻索引之间具有边，其中边的可用取决于当前值和玩家。 

重要的边缘情况是局部结构立即困住一名玩家的情况。 例如，如果一个位置是局部最小值，那么如果被迫移动到具有较小值的邻居，青山可能根本没有有效的移动，从而使其立即失败。 相反，如果丹尼尔从局部最大值开始，他可能会陷入类似的困境。 当两个指针相邻时，会出现另一种棘手的情况，因为阻塞会阻止某些强制移动，并可能意外切断逃生路径。 

## 方法

 暴力破解的想法很简单：对于青山的每个可能的起始索引 x，模拟 Daniel 的所有可能响应，并在由 (x, y,turn) 定义的状态空间上将游戏作为极小极大过程。 每个状态最多转换到两个邻居，因此状态总数为 O(n^2)，每次转换为 O(1)。 即使使用记忆化，在最坏的情况下，可达状态的数量也是二次的，使得这种方法太慢。 

关键的观察是，游戏实际上并不是关于长的交替路径，而是关于青山是否可以迫使丹尼尔进入一个位置，在青山自己陷入困境之前，丹尼尔没有严格的增加动作。 由于两名玩家仅沿着局部比较移动，因此可以根据您在每个方向上单调移动的距离来对每个位置进行分类。 游戏实际上取决于是否存在从起点开始的“主要逃逸方向”，而该逃逸方向不能被对手的对称约束所抵消。 

一种有用的重新表述是将每个位置视为具有两个有向链：一个用于递减移动，一个用于递增移动。 青山只在递减的边缘上行走，丹尼尔只在递增的边缘上行走，他们互相阻挡。 关键的简化是，唯一对赢得开局至关重要的位置是那些不会立即被双方本地统治的位置。 仔细分析相互作用后，条件归结为青山是否可以选择一个不是局部最小值且不会被丹尼尔对称逃逸“中和”的起始位置。 

这导致基于识别排列中的结构模式的线性扫描解决方案，特别是局部极值和交替单调段。

 ## 算法演练

 关键是要了解青山何时可以从起始位置 x 强行获胜。 青山总是移动到一个严格较小的邻居，所以她的移动完全由下降的路径决定。 丹尼尔对称地遵循上升路径。 因为两者都仅限于相邻的动作，所以游戏分解为局部单调的“山谷和山峰”行为。 

## 步骤

 1. 对于每个位置 i，检查它是否是局部最小值，这意味着两个邻居（如果存在）都有更大的值。 如果青山从局部最小值开始，她就没有有效的动作并立即失败。 这会立即从候选人中删除此类职位。 
2. 考虑不是局部最小值的位置。 从这样的位置开始，青山可以移动到至少一个具有较小值的邻居，从而开始一条下降链。 这条链条的结构决定了丹尼尔能否在另一边对称地做出反应。 
3. 观察 Daniel 的最优策略是选择一个位于最大递增路径上的起始 y，并尽可能阻止青山的下降。 这意味着丹尼尔有效地“控制”了增加的部分，而青山必须从一个她的下降路径不会立即被同样强大的上升路径反映的区域开始。 
4.青山唯一稳定的获胜起点出现在局部最大值的位置或位于其左右邻居不都为丹尼尔提供对称响应路径的配置中。 在实践中，这减少了对未被两个邻居严格控制的位置进行计数，从而形成强制占领。 
5. 计算每个位置是否是局部最大值或满足左右邻居之间的严格不平衡条件。 将这些位置视为获胜的开始。 

## 为什么它有效

 游戏动态不允许远程绕过：每一步棋都是严格相邻的，并且每个玩家允许的棋步值都是单调的。 这意味着每场演出都局限于局部单调的走廊。 在这样的走廊中，最佳游戏减少为直接可达性比较，而不是深度分支。 局部极值的分类准确地捕获了玩家是否具有立即强制延续或立即陷阱，并且这些局部陷阱确定性地传播，而无需跨远距离索引进行交互。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    if n == 2:
        print(0)
        return

    ans = 0

    for i in range(n):
        left_bigger = (i == 0 or p[i-1] > p[i])
        right_bigger = (i == n-1 or p[i+1] > p[i])

        # local minimum check
        if left_bigger and right_bigger:
            continue

        ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该代码扫描每个位置并检查它是否是局部最小值。 通过验证两个邻居是否更大（或超出范围，被视为自动更大）来检测局部最小值。 这些职位被排除在外，因为青山无法从这些职位上采取行动。 所有其他职位都被视为获胜候选人。 

n = 2 的特殊情况是明确处理的，因为这两个位置都是移动规则下的局部最小值，并且没有有效的起始位置可以保证获胜。

 ## 边缘情况

 当 n = 2 时，两个位置都被有效地阻止了有意义的比赛，因为任何移动都会立即与对手的强制邻接约束相互作用。 该算法正确返回 0，因为两个位置都满足边界处理下的类局部最小值条件。 

在严格递增排列中，只有第一个位置不是局部最小值。 扫描精确地计算出一个有效的起点，这符合只有最左边的点允许任何初始下降的想法。 

在严格递减排列中，只有最后一个位置不是局部最小值，再次产生恰好一个有效的开始。 该算法通过将缺失的邻居视为自动变大来处理边界，这对于避免相差一错误至关重要。
