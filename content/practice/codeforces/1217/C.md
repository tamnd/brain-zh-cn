 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，并要求计算它的“好”子字符串。 如果子字符串的长度等于其二进制表示形式的十进制值（允许前导零），则该子字符串是好的。 这意味着对于像这样的子字符串`011`，即`3`以十进制表示，只有当其长度也为`3`。 我们的输入由多个查询组成，每个查询都有一个二进制字符串，每个查询的输出是该字符串中好的子字符串的数量。 

这些约束为我们提供了最多 1000 个查询，所有查询的长度总和最多为 200,000。 这意味着任何简单地迭代所有可能的子字符串的算法都太慢，因为生成所有子字符串是$O(n^2)$，可以达到$4 \cdot 10^{10}$最坏情况下的操作。 我们需要一个更接近的解决方案$O(n \cdot \text{small factor})$，在实践中理想的是线性的。 

要观察的边缘情况是带有前导零的子字符串。 例如，`000`有十进制值`0`，因此只有长度为零的子字符串才符合资格，这是不可能的。 另一个微妙的情况是长序列的 0 后跟一个 1，例如，`0001`。 子串如`001`有小数`1`但长度`3`，所以他们不好。 如果粗心的方法没有仔细计算每个子字符串长度的二进制到十进制的转换，则可能会多算或少算。 

## 方法

 简单的方法是考虑每个子字符串，将其转换为十进制，然后检查子字符串长度是否与十进制值匹配。 这在逻辑上是正确的，但需要$O(n^2)$每个查询的迭代次数。 即使将二进制字符串转换为十进制也需要$O(n)$每个子串，所以最坏情况的复杂度是$O(n^3)$，这远远超出了可接受的范围。 

有效解决方案的关键观察是，如果将二进制值解释为整数，则长度超过大约 20 个字符的子字符串就不可能是“好”的。 这是因为子字符串的长度很快变得小于二进制表示的值。 例如，全为 1 的 20 位子串是$2^{20}-1 \approx 10^6$，远远超过我们输入约束中任何字符串的长度。 因此，我们只需要检查从每个位置开始最多大约 20 位的子串。 

此外，我们需要有效地跳过前导零，但如果我们包含它们，我们必须确保不会因为前导零而误算十进制值小于长度的子字符串。 这种见解将问题从对所有子串的二次扫描减少到使用固定小窗口对每个起始位置进行线性扫描。

 | ---| ---| ---| ---|
 | 蛮力 | O(n^3) | O(n^3) | O(1) | O(1) | 太慢了 |

 ## 算法演练

 1.读取查询数量`t`并迭代每个查询。 
2. 对于每个字符串`s`长度`n`,初始化一个计数器`ans = 0`累积好子串的数量。 
3. 循环每个起始索引`i`在字符串中。 
4. 最初跳过前导零或单独考虑它们。 开始构建十进制值`val = 0`。 
5. 对于每个结束索引`j`开始于`i`并扩展最多 20 个字符（或直到字符串结束），更新`val = val * 2 + int(s[j])`。 
6. 计算子串长度为`length = j - i + 1`。 
7. 如果`val == length`, 增量`ans`1. 如果`val > length + 20`，提前中断，因为进一步扩展永远无法满足条件。 
8. 完成所有起始位置后，打印计数器`ans`。 

为什么它有效：不变的是，对于每个起始索引，我们只考虑长度与其十进制值相当的子字符串，这确保我们不会错过任何潜在的好子字符串。 20 个字符的界限就足够了，因为任何更长的二进制数都会超过最大字符串长度，从而保证正确性，而不会迭代不切实际的子字符串长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_good_substrings(s):
    n = len(s)
    ans = 0
    for i in range(n):
        if s[i] == '0':
            continue
        val = 0
        for j in range(i, min(n, i + 20)):
            val = val * 2 + int(s[j])
            length = j - i + 1
            if val == length:
                ans += 1
            if val > n:
                break
    return ans

t = int(input())
for _ in range(t):
    s = input().strip()
    print(count_good_substrings(s))
```该解决方案有效地读取输入并处理多个查询。 内部循环最多只处理 20 个字符，避免超时。 支票`val > n`防止超出可行子串长度的不必要的迭代。
