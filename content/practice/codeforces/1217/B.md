 ## 解决方案
 ## 问题理解

 我们得到了一个具有初始头部数量和攻击类型集合的生物。 每种攻击类型的行为方式都非常具体：使用时，它会去除一定数量的头，但在攻击后，如果该生物仍然活着，它会立即重新长出固定数量的头。 目标是使用尽可能少的攻击次数将正面数量减少到恰好为零。 

关键细节是，攻击的伤害受到当前头部数量的限制，因此，如果该生物的头部数量少于攻击强度，则只需移除剩余的头部。 如果该生物在攻击中幸存下来，它就会获得额外的头，这可能会使未来的进步变得更加困难。 

每个测试用例的输出是将头完全减少到零所需的最小攻击次数，如果没有攻击序列可以实现这一点，则输出为 -1。 

攻击类型数量限制较小，最多 100 种，但攻击头数最多可达 10^9。 这立即排除了任何基于状态的对磁头数量的动态编程。 任何尝试逐步模拟人头计数所有可能状态的解决方案都会太慢，因为状态空间在实践中是无限的。 

当每种攻击类型都会增加网络上的头数时，即使在最好的情况下，也会出现微妙的边缘情况。 在这种情况下，任何单一攻击都不能保证最终进度为零，除非它可以直接从某种可达状态杀死该生物。 

例如，考虑 d = 5 且 h = 10 的攻击。如果该生物有超过 5 个头，则净效果为 +5 个头，这会使情况变得更糟。 不断使用此类攻击的贪婪方法将会发散。 

另一个重要的边缘情况是攻击可以立即杀死该生物。 如果 d ≥ 当前的头，则无论 h 如何，该生物都会立即死亡。 这使得一些攻击在正确的时机使用时会变得异常强大。 

## 方法

 暴力策略会尝试模拟所有可能的攻击序列。 从每个状态，我们应用每次攻击并递归地探索结果，跟踪达到零头所需的最小步骤数。 这在概念上是正确的，因为它探索了完整的选择决策树。 

然而，状态的数量实际上是无限的。 即使我们将状态限制在 x 处，每个操作都可以增加或减少头数，因此搜索空间会无限扩展。 在最坏的情况下，每个状态最多会分支成 n 个新状态，从而导致指数爆炸。 即使对于非常小的输入，这也是不可行的。 

关键的观察结果是，大多数攻击从长远来看要么是有害的，要么只是作为终结动作有用。 如果一次攻击的 h ≥ d，那么当生物的头数超过 d 时使用它会导致头数净增加。 此类攻击不可能成为有效战略的一部分，除非可能作为最后的致命一击。 

另一方面，h < d 的攻击会严格减少“循环”中头部的数量：如果我们在生物还活着时应用此类攻击，则净变化为负值 (d − h)，但受到当前大小的限制。 这些是唯一可以通过多个步骤持续减少人数的攻击。 

这表明了一种贪婪的结构。 我们要反复使用最好的“循环缩小”攻击来尽可能缩小怪物，然后以最好的一击必杀的终结攻击来完成。 由于所有其他攻击的净进度都更差，因此它们无助于获得最佳解决方案。 

因此，我们计算两个量：所有非终止攻击中的最佳净减少量，以及最佳直接杀伤攻击。 如果没有任何攻击可以降低状态或直接杀死它，那么答案是不可能的。

我们模拟重复应用最佳的减少攻击，直到人数变得足够少，最后一击可以杀死它。

 ## 算法演练

 我们根据攻击能否一击消灭怪物将攻击分为两类。 

1、每次攻击都检查满效时能否直接杀死怪物。 当 d ≥ 当前头时会发生这种情况，但由于当前头发生变化，我们改为跟踪所有攻击并将它们视为潜在的终结动作。 
2. 确定最佳的终结攻击，即在某个阶段使用可以杀死怪物的攻击。 在实践中，任何攻击都可能成为终结技，但我们只关心其原始能力 d。 
3. 对于非终结攻击，计算在生存模式下应用时的有效减少量。 每次此类攻击都会将 x 更改为 x − d + h，这是 −(d − h) 的净变化。 只有 d > h 的攻击才有助于减少。 
4. 在所有减少攻击中，选择最大 (d − h) 的攻击。 这是减少重复使用的扬程的最快方法。 
5. 当剩余人数大于任何直接杀戮阈值时，重复应用此最佳减少攻击。 
6. 当人头足够少时，使用最好的终结攻击一招结束战斗。 

### 为什么它有效

 该过程依赖于这样一个事实：任何非终结移动要么减少头的数量，要么增加头的数量。 如果增加它，除了最后一步之外，它不能成为最佳序列的一部分，因为它只会延迟终止。 在所有的减少动作中，总是选择最大的净减少是最优的，因为系统没有依赖于状态的收益或未来奖励，每个操作都是独立的并且效果是线性的。 这使得该过程相当于最小化重复相同步骤的线性成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        
        best_reduce = 0
        best_finish = 0
        
        for _ in range(n):
            d, h = map(int, input().split())
            
            if d >= x:
                best_finish = max(best_finish, 1)
            
            if d > h:
                best_reduce = max(best_reduce, d - h)
        
        if x == 0:
            print(0)
            continue
        
        if best_finish:
            print(1)
            continue
        
        if best_reduce == 0:
            print(-1)
            continue
        
        # Each effective cycle reduces at least best_reduce
        # We approximate minimal steps
        # Actually simulate greedily
        steps = 0
        while x > 0:
            if x <= best_reduce:
                steps += 1
                break
            x -= best_reduce
            steps += 1
        
        print(steps)

if __name__ == "__main__":
    solve()
```该实现将攻击分为减少和完成类别。 如果任何攻击可以立即杀死怪物，则结束标志被设置。 减少值跟踪最强的保证净减少。 

该循环模拟重复应用最强的减少攻击，并在人头数量足够小时最后使用最后一步来完成。 关键的实现问题是确保我们正确处理仅生存攻击并且从不尝试模拟无效状态。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n, x = map(int, input().split())
            best_reduce = 0
            best_finish = False
            
            for _ in range(n):
                d, h = map(int, input().split())
                if d >= x:
                    best_finish = True
                if d > h:
                    best_reduce = max(best_reduce, d - h)
            
            if x == 0:
                out.append("0")
            elif best_finish:
                out.append("1")
            elif best_reduce == 0:
                out.append("-1")
            else:
                steps = 0
                while x > best_reduce:
                    x -= best_reduce
                    steps += 1
                steps += 1
                out.append(str(steps))
        return "\n".join(out)

    return solve()

 ## 边缘情况

 当每次攻击都会增加正面数量（除非是最后一击）时，算法会正确地避免使用它们进行减少。 例如，对于所有攻击，当 d ≤ h 时，best_reduce 保持为零，算法立即返回 -1，除非存在直接杀死。 

当单次攻击可以立即杀死时，例如x = 5和d = 10，解决方案返回1而不模拟任何东西。 这避免了不必要的循环，并反映了终止独立于其他操作的事实。 

当需要重复归约时，算法总是选择最大的 (d − h)，确保没有其他序列可以实现更少的步数，因为任何替代归约在每次移动时都严格较弱。
