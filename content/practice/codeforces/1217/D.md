 ## 解决方案
 ## 问题理解

 我们给出一个有向图，其中每条边都是预先固定的，并且我们必须为每条边分配一个颜色（整数标签）。 该约束与顶点无关，而是与有向循环有关：如果查看单一颜色的所有边，它们不得包含任何有向循环。 

任务是尽量减少使用的颜色数量，同时仍然确保每个单色子图都是非循环的。 

重新解释该要求的一个有用方法是每个颜色类必须形成有向无环图。 我们有效地将边集分解为最少数量的非循环有向子图。 

约束足够小，O(nm) 或 O(m log m) 构造就可以了，因为 n 和 m 都最多 5000。这表明我们可以进行图遍历、重复 DFS 或边上的贪婪构造，而不必担心超出二次的渐近紧性。 

一个天真的想法是任意分配颜色或通过对边缘进行分组，但循环会立即破坏这种尝试。 例如，在有向三角形 1 → 2 → 3 → 1 中，如果所有边共享相同的颜色，则我们已经违反了条件。 这表明，即使是小的强连接组件也会强制使用多种颜色。 

当在不考虑依赖性的情况下处理边时，会出现微妙的失败情况。 例如，在以任意顺序给出边的图中，贪婪地分配颜色而不跟踪可达性可能会产生 DFS 中的后边与前边共享颜色的情况，从而创建单色循环。 正确的方法必须确保参与 DFS 后边结构的任何边在颜色上与其前面的 DFS 树边分开。 

关键的结构见解是，答案与 DFS 树中后边缘的深度紧密相关。 

## 方法

 暴力方向是尝试将所有可能的颜色分配给边缘，将 k 从 1 向上增加，并检查每种颜色是否有效。 有效性检查需要验证每个颜色类别是否是非循环的，这本身需要对每个颜色进行循环检测，通常为 O(n + m)。 即使我们将 k 限制为 m，这也会变成组合，并且在最坏的解释中以 k^m 的形式增长，这是不可行的。 

我们可以通过注意到我们实际上不需要尝试分配来简化搜索空间。 相反，我们可以直接构造一个着色。 

中心观察是有向图中的循环由 DFS 后边暴露。 在 DFS 期间，当我们遍历一条边到当前活动节点时，该边会关闭一个循环。 如果我们确保这些边接收的颜色严格大于它们出现时的 DFS 树深度，我们就可以防止它们与参与同一 DFS 堆栈结构的所有边共享颜色。 

这引出了一个建设性的想法：维护 DFS 访问状态，并根据边在 DFS 树中前进还是后退到活动节点来分配颜色。 前向边缘可以安全地共享颜色 1，因为如果它们遵循 DFS 排序，则它们之间无法形成有向循环。 后边缘必须分配不同的颜色，因为每个后边缘指示相对于 DFS 顺序的依赖性违规。 

仔细的细化表明我们只需要两种颜色。 如果图表没有循环，则一种颜色就足够了。 如果至少有一个后边缘，则两种颜色足以将树/前边缘与后边缘分开，从而防止单色循环。 

问题归结为检测图是否包含 DFS 中可达的有向循环并相应地标记边缘。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n + m) | 太慢了 |
 | 基于 DFS 的构造着色 | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 我们在跟踪节点状态的同时对有向图执行 DFS。 

1. 为图构建邻接列表，还存储每条边的索引，以便我们可以按输入顺序分配颜色。 这是必要的，因为输出与原始边缘排序相关。 
2. 为节点维护一个访问状态数组，该数组具有三种状态：未访问、递归堆栈中处于活动状态、已完全处理。 这使我们能够精确地检测后边缘。 
3. 从每个未访问的节点启动DFS。 该图可能是断开的，因此我们必须覆盖所有组件。 
4.当探索一条边u→v时，我们根据v的状态对其进行分类。如果v未被访问，我们将其视为DFS树边并继续DFS。 
5. 如果 v 当前处于活动状态，则边 u → v 是后边，这意味着它关闭有向循环。 我们指定该边缘颜色为 2。 
6. 如果 v 已被完全处理，则该边缘是前向边缘或交叉边缘。 它无法在 DFS 堆栈上下文中创建循环，因此它被分配颜色 1。 
7. DFS 完成将节点标记为已完全处理。 

如果遇到任何后沿，最终答案使用 k = 2，否则 k = 1。 

### 为什么它有效

 DFS 排序在非后边缘的边缘上产生偏序。 任何不是后边缘的边缘都遵循此顺序，并且不能参与同一颜色类别内的有向循环。 后边缘正是那些通过指向活动递归堆栈来违反此顺序的边缘，这保证了它们负责关闭循环。 通过将它们隔离成一种单独的颜色，我们打破了每个潜在的单色循环，因为每个有向循环在任何 DFS 遍历中都必须包含至少一个后边缘。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, m = map(int, input().split())

g = [[] for _ in range(n)]
edges = []

for i in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append((v, i))
    edges.append((u, v))

color = [1] * m
state = [0] * n  # 0 = unvisited, 1 = active, 2 = done

has_cycle = False

def dfs(u):
    global has_cycle
    state[u] = 1
    for v, idx in g[u]:
        if state[v] == 0:
            dfs(v)
        elif state[v] == 1:
            color[idx] = 2
            has_cycle = True
        else:
            color[idx] = 1
    state[u] = 2

for i in range(n):
    if state[i] == 0:
        dfs(i)

k = 2 if has_cycle else 1
print(k)
print(*color)
```该实现直接对 DFS 分类进行编码。 关键细节是，边缘着色是在我们检查边缘时决定的，具体取决于其目的地是在递归堆栈中还是已经处理过。 递归堆栈检测由状态数组处理，其中值 1 表示活动。 

最终的 k 取决于我们是否遇到过后沿。 如果不存在，则该图已经是 DAG 并且所有边都可以安全地共享颜色 1。 

## 工作示例

 ### 示例 1

 输入：```

1 2
1 3

```所有边形成一个 DAG，因此不会出现后边。 

| 步骤| 边缘| v 的状态 | 类型 | 颜色 |
 | ---| ---| ---| ---| ---|
 | 1 | 1→2 | 未访问过 | 树| 1 |
 | 2 | 1→3 | 未访问过 | 树| 1 |

 | 5 | 1→4 | 完成 | 前进| 1 |

 未检测到循环，因此 k = 1。 

此跟踪确认在 DAG 中，所有边在单一颜色类中保持安全。 

### 示例 2

 考虑一个图表：```
3 3
1 2
2 3
3 1
```这是一个有向循环。 

| 步骤| 边缘| v 的状态 | 类型 | 颜色 |
 | ---| ---| ---| ---| ---|
 | 1 | 1→2 | 未访问过 | 树| 1 |

 这里最后一个边缘关闭了循环并且必须被分开。 

这证实了每个有向循环都会迫使至少一个边缘变成第二种颜色。

 ## 边缘情况

 关键的边缘情况是已经是 DAG 的图。 在这种情况下，不会出现递归堆栈后边缘，因此算法将所有边缘分配颜色 1。这与最佳答案匹配，因为 DAG 根据定义没有循环。 

另一种边缘情况是存在循环但由结构分隔的图，例如两个不相交的循环。 DFS 将检测两个组件中的后边缘，但全局仍然只需要颜色 2。 这种分离之所以有效，是因为每个后边缘都被隔离到第二类中，无论它出现在哪里。 

最后一个微妙的情况是，在某些 DFS 排序中，循环是通过交叉边而不是直接后边形成的。 即使如此，任何有向循环在 DFS 分类中都必须包含至少一个后边缘，因此算法仍然会识别至少一个需要第二种颜色的边缘，从而确保正确性。
