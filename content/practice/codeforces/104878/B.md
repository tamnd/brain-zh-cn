 ## 解决方案
 ## 问题理解

 有 N 个开关，每个开关代表安全系统上的一个引脚。 打开一个引脚只需一秒钟，并且每个引脚只能激活一次。 困难在于每个引脚都监视一组固定的其他引脚。 如果在没有足够多的监视邻居处于活动状态的情况下激活某个引脚，该引脚就会变得危险。 

更准确地说，每个引脚 i 都有一个它监视的其他引脚的列表和一个阈值 K[i]。 当您决定激活引脚 i 时，其监控列表中至少 K[i] 个引脚必须已处于活动状态，否则警报会立即触发。 Pin 1 是目标，我们想知道如果我们选择最佳的激活顺序，它可以安全激活的最早可能时刻（以秒为单位）。 

对于每个引脚，输入描述了它所监视的引脚列表，以及其中有多少引脚必须在按下之前处于活动状态。 输出是一个数字：在所有被认为安全的引脚的某个有效激活序列下，引脚 1 可以被激活所需的最短时间。 

尽管每个引脚都需要一秒钟，但实际的困难不是计时，而是在依赖于先前激活的邻居的约束下进行排序。 

约束足够大，任何尝试测试激活顺序的所有排列的解决方案都立即不可能，因为这将随 N 呈阶乘增长。如果 N 很大，即使对所有状态进行二次或三次检查也会失败，因为所有引脚上的连接总数可能达到很高的值。 

一种天真的但诱人的方法是重复模拟选择：在每一步中，选择当前满足要求的任何引脚并激活它。 然而，微妙的问题是，延迟引脚 1 可能变得不可能，不是因为它被直接阻止，而是因为延迟它会阻止其邻域中足够的支持激活，从而导致其余结构不存在有效排序的级联。 答案取决于延迟单个节点的全局可行性，而不仅仅是本地可用性。 

当一个节点严重依赖于自身间接依赖于它的邻居时，就会出现一个小的说明性失败案例。 例如，如果许多节点需要引脚 1，而这些节点也需要引脚 1 来满足其阈值，则从早期考虑中删除引脚 1 会降低其程度，并可能使许多在引脚 1 已处于活动状态时看似可能的激活序列无效。 忽略这种耦合的贪婪调度将错误地假设这些节点始终可以放置在第一位。 

## 方法

 如果我们尝试直接构建激活顺序，最直接的想法是重复选择当前满足要求的任何引脚，将其标记为激活，并继续直到引脚 1 最终被激活。 如果我们尝试强制 pin 1 在订单中延迟，我们将需要探索其他 pin 的许多可能的激活顺序，并检查 pin 1 是否仍然可以推迟，同时保持所有中间约束有效。 

这种蛮力的观点导致了可能性的爆炸。 每一步都会分支成许多候选引脚，并且在选择前缀后验证是否存在完整排序需要重复重新计算满足条件。 在最坏的情况下，我们正在有效地探索最多 N 个元素的排列，这些排列按 N 阶乘的顺序增长，远远超出任何可行的限制。

关键的观察是我们实际上并不关心完整的订单。 我们只关心在引脚 1 变得不可避免之前可以激活多少个引脚。 如果我们暂时假设引脚 1 不允许被激活，那么剩下的问题就变成了一个封闭问题：我们正在寻找可以激活的最大引脚子集，同时子集中的每个引脚仍然仅使用该子集中的邻居来满足其 K 要求。 如果这样的子集很大，那么这些引脚都可以在引脚 1 之前被激活。如果它很小，则引脚 1 必须更早出现。 

这将问题转化为寻找能够在重复修剪过程中幸存下来的最大节点集。 当前候选集中任何不能满足其要求的节点都不可能包含在内，因此将其删除。 删除节点可能会降低其邻居的满意度，可能会导致进一步删除的级联。 稳定后剩下的正是一组可以在引脚 1 之前以某种有效顺序激活的引脚。 

一旦知道了最大可行设置大小，就可以将引脚 1 立即放置在其后面，从而提供尽可能短的激活时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力排序模拟 | O(N!) | O(N) | 太慢了 |
 | 基于剪枝的可行性收敛 | O(N + 总边数) | O(N + 总边数) | 已接受 |

 ## 算法演练

 我们将引脚 1 视为特殊目标，并暂时禁止它成为早期激活集的一部分。 目标是计算在有必要之前可以激活多少个其他引脚。 

1. 构建一个包含除引脚 1 之外的所有引脚的工作集。每个引脚 i 都以一个计数器开始，该计数器等于其邻居数量也在该工作集中。 如果我们只考虑引脚 1 之外的引脚，该计数器表示它可以依赖多少个已经可用的支持激活。 
2. 初始化一个队列，其中所有引脚 i 不等于 1，其当前计数器严格小于 K[i]。 这些引脚立即无效，因为即使在最好的情况下，如果没有引脚 1，它们也无法满足其要求。 
3. 反复从队列中删除引脚。 当移除引脚 j 时，认为无法在引脚 1 之前的前缀中激活。 
4. 对于仍在工作集中的 j 的每个邻居 i，将其计数器减 1。 该模型模拟了删除 j 会减少 i 的可用支持激活数量的事实。 
5. 如果任何邻居 i 在此更新后下降到其阈值 K[i] 以下，它也会被添加到队列中以进行删除。 
6. 继续，直到不再发生删除。 剩余的引脚形成一个稳定的集合，其中每个节点在该集合内至少有 K[i] 个邻居。 
7. 令剩余组的大小为 M。答案是 M + 1，因为所有 M 个引脚都可以首先被激活，并且引脚 1 必须紧随其后。 

核心思想是，我们正在计算“每个节点内部满足其阈值”条件下的最大封闭子集。 任何违反此条件的节点都不能出现在任何有效调度中的引脚 1 之前，因为即使对剩余节点进行最佳排序也无法增加其可用支持。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())
    adj = [[] for _ in range(n)]
    k = [0] * n
    nr = [0] * n

    for i in range(n):
        parts = list(map(int, input().split()))
        nr[i] = parts[0]
        k[i] = parts[1]
        adj[i] = [x - 1 for x in parts[2:]]

    alive = [True] * n
    alive[0] = False

    deg = [0] * n

    for i in range(n):
        if i == 0:
            continue
        cnt = nr[i]
        for v in adj[i]:
            if v == 0:
                cnt -= 1
        deg[i] = cnt

    q = deque()
    for i in range(1, n):
        if deg[i] < k[i]:
            q.append(i)

    while q:
        u = q.popleft()
        if not alive[u]:
            continue
        alive[u] = False

        for v in adj[u]:
            if v == 0 or not alive[v]:
                continue
            deg[v] -= 1
            if deg[v] < k[v]:
                q.append(v)

    m = sum(alive)
    print(m)

if __name__ == "__main__":
    solve()
```该实现直接反映了修剪过程。 邻接列表存储每个引脚的“报警连接”。 度数数组跟踪每个引脚当前在不包括引脚 1 的工作集中有多少个可用邻居。我们显式地从包含引脚 1 作为邻居的节点的初始计数中减去引脚 1，因为引脚 1 在我们尝试推迟它时不可用。 

队列驱动级联删除过程。 一旦节点变得无效，它就会被删除，并且它的影响会通过降低邻居度来传播。 活动数组可防止重复处理已删除的节点，从而使算法在边缘上保持线性。 

活动节点的最终计数代表在不违反任何约束的情况下可以在引脚 1 之前激活的最大引脚集，因此答案就是该计数。 

## 工作示例

 考虑结构强制特定激活链的样本输入。 

| 步骤| 已删除节点 | 关键程度变化| 活集尺寸|
 | ---| ---| ---| ---|
 | 初始| 无 | 计算的所有度数（不包括引脚 1）| 9 |
 | 删除无效节点 | 多个 K 不足的节点 | 邻里之间的级联减少| 减少|
 | 稳定| 不再有搬迁| 其余全部满足 K | 最终M |

 该过程表明，一旦开始早期强制删除，它们就可以通过依赖关系图传播，从而缩小引脚 1 之前的可行前缀。 

第二个例子有助于阐明独立性。 假设除引脚 1 之外的所有引脚的 K[i] = 0。则任何节点都不会变得无效，因为每个节点都已满足，无需任何邻居。 修剪过程不会删除任何内容，因此所有 N-1 个节点都保留下来，并且引脚 1 可以放在最后，给出答案 N。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(N + E) | 每个节点被删除一次，并且每条边在度更新期间最多被处理一次 |
 | 空间| O(N + E) | 邻接表加上度数和状态数组 |

 这些约束允许连接总数很大，但对所有邻接条目的线性遍历仍然完全符合限制。

 ## 边缘情况

 当引脚 1 严重连接且其移除会显着改变可行性时，就会出现关键的边缘情况。 例如，如果许多节点恰好需要引脚 1 的存在来满足 K，则排除引脚 1 最初会使它们立即无效，并且在任何其他处理之前将它们删除。 该算法可以正确处理此问题，因为初始度数计算已经从每个受影响的节点中减去引脚 1，因此这些节点从一开始就被正确识别为无效并尽早删除。 

当除引脚 1 之外的所有节点的 K[i] 都为零时，会出现另一种边缘情况。在这种情况下，无论顺序如何，每个节点都保持有效。 队列永远不会填满，不会发生删除，并且算法会立即稳定下来，保留除引脚 1 之外的所有节点。最终答案变为 N，这与引脚 1 可以推迟到最后而不违反任何条件的事实相匹配。 

第三种情况涉及长依赖链，其中每次删除都会解锁下一次违规。 基于队列的传播确保每个边的每个递减只处理一次，因此即使在完全链接的最坏情况下，算法也会以线性时间遍历链，同时正确地逐步缩小可行集。
