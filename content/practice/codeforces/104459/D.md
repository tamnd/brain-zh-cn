 ## 解决方案
 ## 问题理解

 我们得到一个连通的无向图和一系列按固定周期轮流的玩家。 每次移动都包括从图中删除一条边。 唯一的限制是图在移除后必须保持连接。 如果玩家移除了断开图表的边，则该玩家所在的组立即失败并且游戏停止。 

有两组玩家，回合顺序由玩家的顺序预先确定。 每个玩家的行为都是自私的，但都具有完全的最佳发挥，我们希望在双方都发挥最佳的情况下确定哪一组可以保证获胜。 

从图表的角度来看，唯一的“坏”举动是移除桥梁，因为这正是连接中断的时候。 所有其他边都可以安全地移除，而不会结束游戏。 游戏继续进行，直到不可能在不断开图形的情况下删除任何边。 

这些约束表明每个测试用例都有一个接近线性的解决方案。 所有测试的顶点和边总数最多为 10^6，因此任何涉及重复图重新计算或每边连接检查的操作都太慢。 任何使用 DFS 模拟删除或在每次移动后重新计算桥的方法都远远超出了可行的限制。 

天真的想法的一个微妙的失败案例是假设桥梁是静态的。 例如，在四个节点的循环中，每条边最初都是非桥的。 移除一条边后，剩余的结构变成一条路径，其中每个剩余的边都是一座桥。 尝试预先计算一次桥并对游戏进行静态推理的策略在这里将会失败，因为安全移动集会不断演变。 

另一个常见的错误想法是贪婪地模拟过程，而不了解最佳游戏并不取决于选择哪些非桥边，而只取决于在图不可避免地变成树之前可以执行多少次此类移动。 

## 方法

 暴力模拟实际上会玩这个游戏：在每个回合中，尝试所有边，检查删除它是否会使用 DFS 或联合查找回滚断开图，并选择避免立即损失的移动。 这已经使每次移动花费 O(m) 次检查，并且每次检查花费 O(n + m)。 由于可能有 O(m) 次移动，因此这会变成 O(m^2) 或更糟，这在 10^5 规模下是完全不可行的。 

关键的观察结果是，游戏并不依赖于安全边缘选择的详细结构。 唯一有意义的区别是保持连通性的安全举措和不可避免地破坏连通性的最终举措之间的区别。 只要图不是树，就总是存在至少一条非桥边，因此玩家可以不断删除边而不会结束游戏。 这个过程一直持续到图变成一棵恰好有 n − 1 条边的树。 到那时，剩下的每条边都是一座桥，所以下一步必须失败。 

这意味着游戏长度已完全确定：我们可以删除边缘，直到只剩下一棵生成树，然后发生额外的强制失败动作。 因此总移动次数为 m − (n − 1) + 1。 

一旦步数确定，唯一剩下的问题就是确定哪个玩家执行最后一步，因为该玩家输了，他们的团队也输了比赛。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(平方米) | O(n + m) | 太慢了 |
 | 最佳计数 | 每次测试 O(1) | O(n) | 已接受 |

 ## 算法演练

 我们计算谁在确定性游戏序列中做出最后一步，然后将该玩家映射到他们的组。

1. 计算将图简化为树所需的不可避免的“安全”删除的数量，即 m − (n − 1)。 这代表所有不会立即输掉比赛的删除。 
2. 为树上的最终强制移除再添加一个移动，给出总移动数 m − n + 2。推理是在到达一棵树之后，恰好进行了一个额外的移动，并且该移动必然会断开图。 
3. 确定最后一步的索引。 由于索引从 0 开始，因此最后一步由玩家 (m − n + 1) mod k 执行。 
4. 从输入字符串中检查该玩家所在的组。 如果是第1组，则第1组输，否则第2组输。 
5.输出对面组为获胜者。 

### 为什么它有效

 不变量是，只要图有超过 n − 1 条边，就至少存在一条不是桥的边，因此当前玩家总能避免立即损失。 因此，当边缘保持在树阈值之上时，没有玩家可以强制游戏提前结束。 一旦图变成一棵树，每条边都是一座桥，因此下一步的行动是唯一确定的并立即失败。 这将整个游戏折叠成一个固定长度的回合序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        k = int(input().strip())
        s = input().strip()
        n, m = map(int, input().split())
        for _ in range(m):
            input()

        last_player = (m - n + 1) % k

        if s[last_player] == '1':
            print(2)
        else:
            print(1)

if __name__ == "__main__":
    solve()
```直接按照推导公式实现。 除了计算 m 之外，永远不需要边本身，因为结构只影响是否可以到达树，而不影响最终不可避免的移动的存在。 

关键细节是计算正确的最后玩家索引：总移动次数为 m − n + 2，因此最终移动对应于基于 0 的回合排序中的索引 m − n + 1。 

## 工作示例

 考虑一个 n = 4 和 m = 5 的小图。该过程总是将其简化为 3 条边的树，然后发生一次被迫失败的移动。 因此，总移动次数为 5 − 4 + 2 = 3 次移动。 最后一步是玩家 (5 − 4 + 1) mod k = 2 mod k。 

| 步骤| 剩余边缘| 移动类型| 玩家|
 | ---| ---| ---| ---|
 | 1 | 5 → 4 | 安全| 0 |
 | 2 | 4 → 3 | 安全| 1 |
 | 3 | 3 → 2 | 失去| 2 |

 这表明，无论在第一步中选择了哪些边，一旦到达一棵树，最后一步就会在结构上受到强制。 

现在考虑一个更密集的图，其中 m 远大于 n。 假设n = 5且m = 10。图在成为树之前可以减少到4条边，因此存在6个安全着法，随后是1个强制失败着法。 失败玩家的身份仅取决于 (m − n + 1) mod k，而不取决于图拓扑。

 ## 边缘情况

 一个关键的边缘情况是图一开始就已经是一棵树了。 在这种情况下，根本没有安全的举动，因为每条边都是一座桥。 公式仍然有效：m = n − 1 给出 m − n + 1 = 0，因此第一个玩家（玩家 0）被迫移除一条边并立即失败。 输出仅取决于符合规则的玩家 0 的组。 

另一种情况是当图很稠密时，例如完整图。 即使存在许多边，游戏仍然只取决于在到达生成树之前必须删除多少边。 结构并不重要，因为非桥边始终存在，直到达到树阈值，因此计算出的移动计数仍然有效。 

最后，当 k 大于移动次数时，只有模行为重要。 玩家的循环正确重复，失败的玩家索引仍然是 (m − n + 1) mod k，因此无论 k 与 m 相比有多大，组分配都保持一致。
