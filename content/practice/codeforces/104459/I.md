 ## 解决方案
 ## 问题理解

 我们有一棵树，其顶点标记为 1 到 n。 标签本身定义了一个线性顺序，我们被要求查看标签的每个间隔 [l, r]。 对于每个这样的区间，我们精确地获取标签位于其内部的顶点，并考虑原始树中这些顶点导出的子图。 任务是计算有多少个标签间隔导致了一个连通图，这意味着当限制在树的边缘时，所有选定的顶点都位于单个连通分量中。 

关键点是连通性不是相对于数值区间结构本身，而是相对于原始树边。 间隔仅定义包含哪些顶点，而树结构定义它们如何交互。 

约束很大：每个测试用例 n 可以达到 3 × 10^5，测试的总和也以 3 × 10^5 为界。 这排除了任何使用 BFS 或 DFS 显式检查每个间隔的连通性的解决方案，因为在最坏的情况下有 θ(n^2) 个间隔。 即使 O(n^2) 增量检查也太慢了。 每个测试用例我们需要接近线性或接近线性的东西。 

当人们假设连接在时间间隔内表现得单调时，就会出现一种朴素方法的微妙故障模式。 例如，人们可能认为如果 [l, r] 已连接，那么 [l, r+1] 也应该保持连接。 这是错误的，因为添加新顶点可能会在导出子图中引入完全隔离的节点。 

作为一个具体的例子，考虑一棵形状像星形的树，以 1 为中心，连接到所有其他顶点。 如果区间为 [2, 3]，则导出的子图是断开的，因为两者都是没有中心的叶子。 然而，[2,3,1]立即连接起来。 这表明连通性取决于两个端点，而不仅仅是间隔增长。 

另一个常见的陷阱是假设连通性仅取决于边界顶点。 在类似路径的结构中，内部结构非常重要，即使端点已连接，缺少单个内部顶点也会破坏连接性。 

## 方法

 暴力方法会枚举每个区间 [l, r]，收集其中的所有顶点，并运行仅限于这些顶点的 DFS 或 BFS 以检查它们是否形成单个组件。 这是正确的，但每个间隔的成本为 O(n)，在最坏的情况下导致总工作量为 O(n^3)，或者在仔细增量重用的情况下最多为 O(n^2)，这仍然远远超出了限制。 

结构上的突破来自于注意到一棵树恰好有 n − 1 条边并且没有环。 对于顶点 S 的任何子集，导出的子图当且仅当它恰好包含 |S| 时才连通。 − 这些顶点中有 1 条边。 “至少 |S| − 1 条边意味着已连接”属性特别成立，因为没有可用于在没有连接的情况下增加边计数的周期。 

这将问题从连通性检查转变为计数问题：对于每个区间，我们只需要知道有多少条树边的两个端点都在该区间内。 

现在的任务是，对于滑动区间 [l, r]，维护完全包含在其中的边的数量。 我们可以使用两个指针动态地维护它。 当我们扩展 r 时，我们激活顶点 r 并计算它的邻居有多少已经处于活动状态。 当我们向前移动 l 时，我们停用顶点 l 并减去将 l 连接到仍然活动的顶点的边的贡献。 

这将问题转化为在移动窗口上维护单个动态值，而不是从头开始重新计算连接性。

 | 暴力破解（每个时间间隔的 BFS）| O(n^2·n) | O(n^2·n) | O(n) | 太慢了|

## 算法演练

 我们独立处理每个测试用例。 为了清楚起见，我们维护一个滑动窗口 [l, r]、一个布尔数组 active[v] 指示顶点当前是否在区间内，以及一个计数器 cnt 存储当前有多少个树边完全位于区间内。 

1. 初始化l = 1，r = 0，cnt = 0，并将所有顶点标记为非活动状态。 
2.将r从1逐步展开到n。 当我们包含一个新顶点 r 时，我们会激活它，并且对于 r 的每个邻居 v，如果 v 已经处于活动状态，我们会递增 cnt，因为边 (r, v) 现在完全位于区间内。 

此步骤确保 cnt 始终反映插入后内部边的准确数量。 
3.添加r后，我们尝试调整l，使当前窗口“有效”。 我们知道大小为 k 的连通区间必须满足 cnt = k − 1，其中 k = r − l + 1。因此，当条件不成立或有利于向前移动时，我们会缩小 l，在删除顶点时更新 cnt。 
4. 删除顶点 l 时，我们停用 l，并且对于仍处于活动状态的 l 的每个邻居 v，我们递减 cnt，因为这些边不再完全包含在区间中。 
5. 对于每个 r，一旦调整了窗口，我们就计算有多少个起始位置 l 产生了以 r 结尾的有效区间。 每次不变式 cnt = (r − l) 成立时，我们就可以安全地添加贡献。 

关键是两个指针都只向前移动，并且每条边都被添加和删除恒定的次数。 

### 为什么它有效

 树中的顶点子集在形成树本身时恰好形成连接的诱导子图。 由于原始图是非循环的，因此任何导出子图也是非循环的，因此连通性相当于恰好具有 |S| − 1 条边。 该算法为每个间隔 [l, r] 动态维护此类边的准确数量。 由于对 cnt 的每次更新都精确对应于添加或删除顶点并考虑所有关联边，因此 cnt 始终与真实的诱导边计数匹配。 两指针过程会探索所有区间而不重复，因此每个有效区间都会被精确计算一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)

    active = [False] * (n + 1)
    cnt = 0

    ans = 0
    l = 1

    for r in range(1, n + 1):
        active[r] = True
        for v in g[r]:
            if active[v]:
                cnt += 1

        while l <= r:
            # check if current window can be valid
            k = r - l + 1
            if cnt < k - 1:
                break
            ans += 1
            # move l forward after counting this valid interval
            active[l] = False
            for v in g[l]:
                if active[v]:
                    cnt -= 1
            l += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该代码维护树的邻接列表和顶点标签上的滑动窗口。 数组 active 跟踪哪些顶点当前位于 [l, r] 内。 当在右端添加顶点时，我们仅检查其邻接列表并根据已活动的邻居更新 cnt，这避免了从头开始重新计算边计数。 

当从左侧收缩时，我们对称地删除顶点并减去消失的边的贡献。 while 循环确保对于每个固定的 r，我们尽可能地推进 l，同时仍然满足连接所需的边缘条件。 

一个常见的实现陷阱是忘记当两个端点都变为活动状态时，每个边都会被精确计数一次，因此每个增量和减量都必须是对称的。 另一个微妙的问题是确保 l 只向前移动，这保证了线性复杂性。

 ## 边缘情况

 一个关键的边缘情况是，即使端点在标签空间中相邻，连接也会失败。 例如，星形树中的区间 [2, 3] 不包括中心，因此 cnt = 0 而 k − 1 = 1，并且算法正确地拒绝它，因为它跟踪边缘而不是端点。 

另一种情况是单个顶点区间 [i, i]，其中 k = 1，所需条件是 cnt = 0。由于单个顶点内不存在边，因此每个这样的区间都会自动计为有效，与连通性的定义相匹配。 

最后，当树是一条路径时，每个区间都是连接的，算法稳定地维持所有活动窗口的 cnt = k − 1，不会触发过早收缩，从而确认了两指针不变量在最大连接情况下表现一致。
