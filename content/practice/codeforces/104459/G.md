 ## 解决方案
 ## 问题理解

 我们得到了一系列值，从空数组开始，逐个插入到二进制堆结构中。 每次插入都使用“冒泡”过程，但堆属性的方向不固定。 对于每个插入的值，操作要么被视为最小堆插入，要么被视为最大堆插入，具体取决于隐藏的二进制决策字符串。 

在所有插入之后，我们只看到两件事：值的插入顺序，以及所有堆操作之后生成的最终数组。 任务是重建一个二进制字符串，指示每个插入的行为是否类似于最小堆步骤或最大堆步骤，以便可以准确地生成给定的最终数组。 如果可以进行多次重建，我们必须输出字典顺序最小的一个。 

堆插入规则很重要，因为它决定冒泡何时停止。 在最小堆插入中，当父级大于子级时，我们向上交换。 在最大堆插入中，当父级小于子级时我们会进行交换。 因此，停止条件根据所选择的模式而不同。 

约束足够大，任何模拟每次插入或回溯所有二进制字符串的所有可能性的方法都是不可能的。 每个测试用例的 n 高达 10^5，总 n 高达 10^6，我们需要本质上线性或近线性的重建。 

一个微妙的困难是，在任一规则下都不能保证最终数组是有效的堆。 这意味着我们不是在验证堆，而是重建可能产生堆的不一致行为。 

重要的边缘情况：

 问题之一是价值观相同。 如果 vi 等于 vj，则交换在值空间中毫无意义，因此多种堆模式可能会产生相同的转换。 仅基于比较的天真贪婪可能会错误地将相等视为允许两个方向。 

另一个问题是插入路径重叠。 稍后的插入可能会扰乱早期的结构，从而使贪婪的局部决策无效。 例如，早期选择最小堆可能会在以后强制执行不可能的配置，即使最大堆选择可行。 

最后的边缘情况是，最终的数组可能看起来局部一致，但全局不可能，这意味着我们必须检测矛盾而不是假设可行性。 

## 方法

 一个暴力的想法是尝试每个可能的长度为 n 的二进制字符串，模拟每个字符串的堆插入，并将结果数组与目标最终数组进行比较。 每次插入的成本为 O(log n)，因此一次完整模拟的时间复杂度为 O(n log n)。 超过 2^n 个选择，这是一个天文数字，即使对于很小的 n 来说也是不可能的。 

关键的观察是我们不需要独立模拟所有选择。 相反，我们可以从最终的堆结构开始向后推导，推理出什么样的插入会产生每个最终位置。 一旦交换路径已知，插入过程就是确定性的，并且每个元素的最终位置是通过沿其冒泡路径进行比较来确定的。 

关键的结构是每个插入仅沿着单个根路径向上移动，并且在每一步中，通过将移动元素与其父元素进行比较来控制决策。 这在隐式堆树的每个边缘上创建了一个约束系统：无论是否发生交换，所选模式（最小或最大）必须与该比较一致。 

这使我们能够增量地重建二进制字符串。 我们通过检查与最终数组结构上已建立的约束的一致性来确定每个插入的行为是否必须像最小堆或最大堆一样。 如果两者都可能，我们选择字典顺序较小的选项，该选项始终为“0”（最小堆）。

重建变成了带有可行性检查的贪婪分配，并由沿着冒泡路径的局部验证支持。

 ## 算法演练

 我们按顺序处理插入，同时维护必须演变成最终数组的堆结构。 这个想法是重建每个插入值必须发生的交换才能到达其最终位置。 

1. 对于每个值 vi，我们知道它在数组 a 中的最终位置。 我们从概念上模拟将 vi 插入到之前步骤构建的堆中，并尝试强制它准确地落在最终数组中出现的位置。 
2. 我们模拟从插入位置到根的冒泡路径，但我们尚未修复比较是否表现为最小堆或最大堆。 相反，我们测试每个父子比较所施加的约束。 
3. 在节点与其父节点之间的每个步骤中，我们检查需要什么：

 如果 vi 小于其父级，则最大堆插入将立即停止在该边缘处的交换，而最小堆将继续交换。 

如果 vi 大于其父级，则会发生相反的行为。 
4. 我们测试 bi 的两种可能性。 对于 bi = 0（最小堆），我们要求路径上的每个交换或停止条件都与最小堆规则一致。 对于 bi = 1，我们检查与最大堆规则的一致性。 
5. 如果两种模式都有效，我们选择 bi = 0 以最小化字典顺序。 
6. 如果两种模式都不能产生 vi 所需的最终位置，我们就断定该配置是不可能的。 

### 为什么它有效

 每次插入都在堆中定义一条向上路径，并且沿着该路径，行为完全由相邻节点之间的比较确定。 唯一的自由度是当父子比较有利于最小堆或最大堆逻辑时是否会发生交换。 

这将每次插入变成了链上的局部可行性问题。 由于后来的插入不会修改先前完成的路径内的相对顺序，除非通过最终数组中已考虑的交换，因此一致性会降低以确保每个插入路径至少允许比较规则的一种有效解释。 

因为我们总是在可能的情况下选择最小堆，所以最终的字符串在所有有效分配中按字典顺序是最小的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        v = list(map(int, input().split()))
        a = list(map(int, input().split()))

        pos = {}
        for i, x in enumerate(a):
            pos[x] = i + 1

        # heap array (1-indexed simulation)
        heap = [0]

        res = []

        ok = True

        for i in range(n):
            x = v[i]
            heap.append(x)
            idx = len(heap) - 1

            # try min-heap first (0)
            def check(is_max):
                cur = idx
                val = heap[cur]
                temp = heap[:]

                while cur > 1:
                    p = cur // 2
                    if is_max == 0:
                        if temp[p] <= temp[cur]:
                            break
                    else:
                        if temp[p] >= temp[cur]:
                            break
                    temp[p], temp[cur] = temp[cur], temp[p]
                    cur = p
                return temp

            # try min heap
            final_min = check(0)
            final_max = check(1)

            if final_min == a:
                res.append('0')
                heap = final_min
            elif final_max == a:
                res.append('1')
                heap = final_max
            else:
                ok = False
                break

        print("".join(res) if ok else "Impossible")

if __name__ == "__main__":
    solve()
```该实现直接模拟每个元素的两种插入模式，并检查是否会导致所需的最终数组。 堆数组是增量重建的，始终与迄今为止所选择的模式保持一致。 

关键的微妙之处在于，我们必须在每次接受插入后更新堆状态，因为后来的插入取决于确切的中间结构。

 ## 边缘情况

 一种边缘情况是单元素堆。 插入不执行任何操作，因此最小和最大解释都会产生相同的结果。 该算法正确地接受字典顺序上最小的选择，产生`0`。 

另一个边缘情况涉及严格的单调序列。 如果值增加，最小堆行为倾向于允许冒泡，而最大堆通常会提前停止。 该算法通过检查哪种模式与最终结构完全匹配来解决这个问题，从而防止错误的贪婪假设。 

第三种边缘情况是最小模拟和最大模拟都不与最终数组匹配。 这正确地触发了不可能。 例如，违反所需父子关系的向上和向下堆一致性的最终数组不能由任何有效堆插入序列产生。 

在所有情况下，正确性来自于验证每个插入的完全模拟一致性，而不是仅仅依赖于局部比较。
