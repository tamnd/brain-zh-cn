 ## 解决方案
 ## 问题理解

 我们得到一组变量，每个变量代表一个隐藏数字。 我们不知道它们的值，但我们得到了“变量 a 严格大于变量 b”形式的严格排序约束的集合。 这些约束定义了一个有向图，其中每条边迫使一个节点具有比另一个节点更大的值。 

对于每个索引 k，我们被问到是否可以为所有变量分配实际值，以便满足每个约束，并且第 k 个变量成为所有 n 个变量的中值。 由于 n 是奇数，中位数是正好 (n−1)/2 个值小于它且 (n−1)/2 个值大于它的元素。 

一般来说，约束可能不一致，但问题并不要求我们构造有效的分配。 相反，我们只需要独立确定每个节点作为候选中值的可行性。 

重要的约束是每个测试用例 n 最多为 100，并且测试用例的总和最多为 2000。这立即表明每个测试用例的 O(n3) 是可以接受的，而诸如指数枚举或每个节点重复的繁重图重新计算之类的任何操作都必须小心控制。 

一个天真的错误是假设只有直接边缘才重要。 例如，如果我们只检查 k 是否至少有 (n−1)/2 个传入或传出边，我们就会错，因为传递含义很重要。 如果 1 > 2 且 2 > 3，则即使没有直接边，1 > 3 也是如此。 

另一个微妙的失败案例是假设图始终是非循环的。 它可能包含矛盾，但由于值是实数，因此有向循环迫使不可能。 例如，1 > 2、2 > 3、3 > 1 是不可能的。 任何正确的解决方案都必须隐式或显式地考虑可达性结构，而不仅仅是直接边缘。 

## 方法

 暴力的想法是尝试分配与约束一致的实际数值，然后测试所选节点是否可以定位为中位数。 我们可以想象生成所有拓扑序或偏序的所有线性扩展，然后检查第 k 个节点是否可以落在中间位置。 这很快就变得不可行，因为线性扩展的数量在最坏的情况下呈阶乘增长，达到 O(n!) 配置。 

关键的观察是我们不需要实际值，只需要相对可达性。 如果节点 u 可以通过有向边到达 v，则在任何有效分配中 u 必须始终大于 v。 这意味着对于任何候选k，从k可达的所有节点必须严格小于k，并且可以到达k的所有节点必须严格大于k。 这两组定义了相对于 k 的强制位置。 

因此，要使 k 成为中位数，被迫小于 k 的节点数量最多必须为 (n−1)/2，而被迫大于 k 的节点数量也必须最多为 (n−1)/2。 如果任何一方超过限制，k 永远不能位于中位数，因为这些关系在每个有效分配中都是不可避免的。 

这将问题简化为计算从每个节点到有向图中每个节点的可达性，这可以使用 BFS/DFS 或传递闭包方法来完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解订单| O(n!) | O(n) | 太慢了|
 | 每个节点的可达性（每个节点的 Floyd / BFS）| O(n3) 或 O(n(n+m)) | O(n²) | 已接受 |

 ## 算法演练

 我们将约束建模为有向图，其中边 a → b 意味着 a 必须大于 b。 

然后我们计算所有节点对之间的可达性。 由于 n 很小，Floyd-Warshall 或每个节点重复的 DFS/BFS 就足够了。 

计算可达性后，我们独立评估每个节点 k。

1. 根据约束构建有向图。 每个关系 a > b 都成为一条边 a → b。 
2. 计算可达性，以便我们知道 u 是否被迫大于 v，无论是直接还是间接。 这给出了图的传递闭包。 
3. 对于每个节点k，计算它可以到达多少个节点。 在任何有效的分配中，这些节点都必须严格小于 k。 
4.同时统计有多少个节点可以达到k。 这些都是必须严格大于 k 的节点。 
5. 设smaller[k]为从k可到达的节点数，larger[k]为可到达k的节点数。 
6. 当且仅当较小[k]和较大[k]都至多(n−1)/2时，节点k可以是中值。 

该条件是对称的，因为所有剩余节点（与 k 不可比较的节点）都可以在强制较小和较大组之间灵活分配值。 

### 为什么它有效

 可达性关系捕获了约束所隐含的每个强制比较。 任何有效的分配都必须尊重所有有向路径，而不仅仅是直接边缘。 因此，在每个可行的分配中，从 k 可到达的每个节点都严格低于它，而到达 k 的每个节点都严格高于它。 

如果任一侧超过 (n−1)/2，则该侧有太多强制元素，无法将 k 置于中间位置。 如果两者都在限制范围内，我们可以通过将所有强制较小的节点放置在 0 以下，将较大的节点放置在 0 以上，并将剩余的不受约束的节点在 0 附近任意分布而不违反任何约束来分配值。 这样就保证了可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [[False] * n for _ in range(n)]

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a][b] = True

    # Floyd-Warshall transitive closure
    for k in range(n):
        for i in range(n):
            if g[i][k]:
                for j in range(n):
                    if g[k][j]:
                        g[i][j] = True

    res = []
    limit = (n - 1) // 2

    for i in range(n):
        smaller = 0
        larger = 0

        for j in range(n):
            if g[i][j]:
                smaller += 1
            if g[j][i]:
                larger += 1

        if smaller <= limit and larger <= limit:
            res.append('1')
        else:
            res.append('0')

    print("".join(res))

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```该解决方案首先构建一个布尔邻接矩阵来表示严格比较。 Floyd-Warshall 用于传播传递性，以便正确标记每个可达关系。 

对于每个候选中值索引，我们将传出可达性计算为强制较小元素，将传入可达性计算为强制较大元素。 阈值比较直接编码该节点是否可以被置于第(n+1)/2个等级。 

一个常见的实施错误是忘记可达性必须是可传递的。 如果没有 Floyd-Warshall 或 DFS 闭包，计数就会低估约束并错误地将无效中位数标记为有效。 

## 工作示例

 考虑一个小情况，其中 n = 5，约束为 1 > 2、3 > 2、2 > 4、2 > 5。传递闭包后，节点 2 到达 4 和 5，并且由 1 和 3 到达。 

| 节点 k | 较小 (k →) | 较大 (→ k) | 有效 |
 | --- | --- | --- | --- |
 | 1 | 2,4,5 数 3 | 0 | 是的 |
 | 2 | 4,5 数 2 | 1,3 数 2 | 是的 |
 | 3 | 2,4,5 数 3 | 0 | 是的 |
 | 4 | 0 | 1,2,3 数 3 | 是的 |
 | 5 | 0 | 1,2,3 数 3 | 是的 |

 该跟踪显示了传递闭包如何将约束传播到直接边缘之外，以及中位数可行性如何仅取决于强制排序计数。 

现在考虑循环矛盾情况 n = 3 且 1 > 2, 2 > 3, 3 > 1。 

| 节点 k | 较小| 更大| 有效 |
 | --- | --- | --- | --- |
 | 1 | 2,3 | 2,3 | 没有|
 | 2 | 3,1 | 1,3 | 没有|
 | 3 | 1,2 | 1,2 | 没有|

 每个节点都被迫高于或低于太多其他节点，从而立即违反可行性。 该算法正确地拒绝所有节点，因为两个计数都超过了中值阈值。

 ## 边缘情况

 一个微妙的边缘情况是当一个节点与许多其他节点无法比较时。 例如，如果没有到达或来自 k 的路径，则两个计数都为零，并且该节点始终有效，因为它可以放置在排序中间的任何位置。 

另一种情况是接近完全的顺序，其中一个节点支配许多其他节点，但仍保持在中值阈值内。 只要其强制的较小和较大集合不超过 (n−1)/2，该算法就正确地允许这样的节点，即使图看起来严重倾斜。 

最后，循环组件自动创建节点之间的相互可达性，同时膨胀较小和较大的计数，并在循环大到足以违反中值容量时强制拒绝。
