 ## 解决方案
 ## 问题理解

 我们在网格上绘制了几个水平线段。 每个线段都位于不同的水平线上：第 i 个线段位于高度 y = i 处，跨度从 x = li 到 x = ri，覆盖这些端点之间的所有整数 x。 

我们可以将标记放置在整数网格点上，但有严格的约束：任何两个标记都不能共享相同的 x 坐标。 换句话说，每个整数 x 位置最多可以在所有标记中使用一次，尽管我们可以为该 x 选择任何整数 y。 

如果一个线段上至少有一个标记，则该线段被视为“被覆盖”，这意味着我们在其区间 [li, ri] 中选择了某个 x 并在 (x, i) 处放置了一个标记。 我们的目标是最大限度地增加多少细分受众群至少收到一个此类代币。 

该结构将问题简化为每个段最多选择一个整数 x，同时确保所有选定的 x 值全局不同。 每个选定的 x 都可以准确地分配给其区间包含该 x 的一个线段。 

约束允许每个测试用例最多 10^5 个段，并具有多个测试用例。 因此，任何解决方案都必须接近 O(n log n) 或更好。 对所有候选分配进行二次甚至 O(n^2) 贪心检查将无法扩展。 

当段严重重叠时，会出现微妙的边缘情况。 例如，如果许多段共享一个公共小区间，如[1, 2]，则只有其中一个可以使用x = 1，另一个可以使用x = 2，因此即使有很多段，最多也可以满足两个。 在没有全局协调的情况下分配“间隔中第一个可用的 x”的幼稚方法将很快在如此密集的重叠中失败。 

当间隔嵌套时会出现另一种边缘情况。 例如，[1, 10]、[2, 9]、[3, 8]。 通过左端点处理的天真贪婪可能会糟糕地分配早期的大间隔并阻止更紧密的间隔，从而错误地减少总计数。 

## 方法

 如果我们忽略效率，最直接的想法是独立对待每个段，并为每个段尝试所有可能的 x 位置，检查我们是否可以全局分配不同的 x 值。 这成为线段和整数点之间的匹配式问题。 由于 x 的范围高达 10^9，因此显式构建图是不可能的，甚至迭代所有候选 x 值也是不可行的。 

一种稍微结构化的暴力方法是压缩所有端点并在检查冲突时尝试贪婪地分配。 即便如此，对于每个段，我们可能会扫描许多候选 x 值，从而在间隔很大且严重重叠的最坏情况下导致 O(n^2) 行为。 

关键的观察结果是，我们实际上并不关心 x 坐标之外的网格几何结构。 每个段仅提供对单个整数资源（x 值）的区间约束，并且每个 x 只能使用一次。 所以问题就变成了：选择尽可能多的区间，这样我们就可以在每个选定的区间内选择一个不同的整数。 

这是经典的调度式最大化，但有一个变化：我们不是将时间间隔分配给时间槽，而是将时间槽（x 值）分配给时间间隔，并且每个时间槽只能使用一次。 正确的贪心方向是按 x 的递增顺序分配令牌，同时始终选择迫使我们最早采取行动的部分。 

标准转换是从左到右扫描 x，维护所有已开始的段 (li ≤ x)，并始终将 x 分配给仍然可用的具有最小右端点的段。 这是最优的，因为对最早到期的段使用 x 可以保留较长间隔的灵活性。 

这会导致以 ri 为键的最小堆的贪婪。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力间隔检查 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 通过右端点扫描线 + 最小堆 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 按左端点 li 升序对所有线段进行排序。 当我们从左到右扫描 x 时，这使我们能够知道段何时可用。 扫描确保我们永远不会错过仍然可以分配未使用的 x 的段。 
2. 在已排序段上初始化指针 i、空的最小堆和计数器答案 = 0。堆将存储当前有资格获取当前 x 的所有段的右端点 ri。 
3. 概念上从 1 向上迭代 x，但实际上我们使用排序的端点直接在相关坐标之间跳转。 在每一步中，我们首先将 li ≤ x 且尚未考虑的所有段插入到堆中。 这些正是仍然可以使用该 x 的段。 
4. 从堆中删除任何 ri < x 的段，因为它们不再能被任何未来的 x 满足。 这些间隔已经是不可能的，必须被丢弃。 这种修剪对于避免浪费分配至关重要。 
5.如果堆非空，则将当前x分配给ri最小的段（弹出堆最小值）。 然后我们将答案加一，因为我们已经成功满足了一个细分市场。 此选择是最优的，因为它首先消耗最受约束的段，为以后的 x 值留下更灵活的段。 
6. 继续向前移动 x，重复该过程，直到处理完所有段并且没有剩余的活动候选者为止。 

为什么这种顺序有效与截止日期的结构有关。 每个段都希望在其区间内有一个唯一的 x。 将较小的可用 x 值分配给最严格的间隔可确保我们永远不会在稍后也可以生存的段上“浪费”小 x 值，这会阻塞更严格的段。 

保持的不变量是，在任何 x 处，堆恰好包含使用某些未来 x ≥ 当前 x 仍然可以满足的段，并且我们总是将当前 x 分配给其中具有最小可能期限的段。 这保留了最大的未来可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        segs = []
        for _ in range(n):
            l, r = map(int, input().split())
            segs.append((l, r))
        
        segs.sort()
        
        import heapq
        heap = []
        ans = 0
        i = 0
        
        # We simulate events: either new segment starts or we assign a point
        # Instead of iterating x up to 1e9, we jump by processing events implicitly
        current_x = 0
        
        while i < n or heap:
            if not heap:
                current_x = segs[i][0]
            
            while i < n and segs[i][0] <= current_x:
                heapq.heappush(heap, segs[i][1])
                i += 1
            
            while heap and heap[0] < current_x:
                heapq.heappop(heap)
            
            if heap:
                heapq.heappop(heap)
                ans += 1
                current_x += 1
            else:
                if i < n:
                    current_x = segs[i][0]
        
        print(ans)

if __name__ == "__main__":
    solve()
```该代码在 x 上实现扫描线，同时维护按右端点排序的堆中的活动段。 指针 i 确保每个段只插入一次。 堆清理会删除当前 x 不再满足的段。 一旦选择了一个有效的段，我们就会消耗一个单位的 x 并继续前进。 

一个微妙的地方是跳转逻辑：当堆为空时，我们不会将x逐一递增到下一个段，而是直接跳转到下一个段的左端点。 这可以避免迭代未使用的整数坐标，并使运行时输入大小与排序和堆操作保持线性。

```我们处理按 l 排序的段：(1,3)、(2,2)、(2,4)。 

| x| 已插入 | 堆 (ri) | 选择| 回答 |
 | ---| ---| ---| ---| ---|
 | 1 | (1,3) | [3] | (1,3) | 1 |

 | 3 | - | [4] | (2,4) | 3 |

现在考虑一个严重重叠的情况：

 输入：```
4
1 2
1 2
1 2
1 2
```当 x = 1 时，所有四个间隔均处于活动状态。 当 x = 1 时，我们选择一个，当 x = 2 时，我们选择另一个，之后就不再有可用的 x 值了。 堆保证我们恰好分配两个段并且不能超过这个值，因为所有可行位置的并集中只有两个整数 x 值。 

这表明可行性受到区间重叠和 x 值的全局唯一性的限制。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    import heapq

    input = sys.stdin.readline
    T = int(input())
    out = []
    for _ in range(T):
        n = int(input())
        segs = [tuple(map(int, input().split())) for _ in range(n)]
        segs.sort()

        heap = []
        i = 0
        ans = 0
        cur = 0

        while i < n or heap:
            if not heap:
                cur = segs[i][0]
            while i < n and segs[i][0] <= cur:
                heapq.heappush(heap, segs[i][1])
                i += 1
            while heap and heap[0] < cur:
                heapq.heappop(heap)
            if heap:
                heapq.heappop(heap)
                ans += 1
                cur += 1
            else:
                if i < n:
                    cur = segs[i][0]
        out.append(str(ans))
    return "\n".join(out)

 ## 边缘情况

 对于 [1,2]、[1,2]、[1,2]、[1,2] 等相同区间，堆始终包含 x = 1 处的四个候选。该算法在 x = 1 处分配一个，在 x = 2 处分配另一个，之后所有剩余段要么已使用，要么已过期。 堆确保我们永远不会尝试分配超过可用的 x 值。 

对于诸如 [1,10]、[2,9]、[3,8] 之类的嵌套区间，早期 x 处的堆包含所有三个区间，但算法会尽可能优先考虑以 8 结尾的区间。 每个分配消耗一个 x，并且所有三个都成功匹配，这表明早期的贪婪选择不会阻碍可行性。 

对于 [1,1] 和 [100,100] 等稀疏区间，指针直接在相关 x 值之间跳转。 当堆为空时，我们跳转到下一个 li，而不是迭代未使用的坐标。 这避免了关于连续分配的错误假设，并保持正确性仅与活动段相关。
