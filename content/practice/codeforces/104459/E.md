 ## 解决方案
 ## 问题理解

 随着时间的推移，我们会收到一系列的图书请求，其中每个请求都要求一本特定的图书。 有一张小桌子，最多可以容纳$k$随时都有不同的书籍。 最初，桌子是空的。 

当请求一本书时，可能会发生两件事。 如果这本书已经在桌子上，则不会从书架上取任何东西。 如果这本书不在桌子上，则必须将其从书架上取出，这算作取操作。 如果桌子已经满了，当需要取一本新书时，必须先删除一本现有的书，规则是我们总是删除最近最少使用的书，即最近访问时间最远的书。 

我们被要求计算每个可能的办公桌容量$k = 1 \ldots n$，在这个 LRU 规则下，BaoBao 会从书架上取一本书多少次。 

输入的大小迫使我们仔细思考。 每个测试用例最多可以有$10^5$请求，所有测试用例的总数是$10^6$。 为每个独立模拟 LRU 的解决方案$k$立刻就太慢了，因为每次模拟都会花费$O(n)$，导致$O(n^2)$每个测试用例的总体工作。 

一个天真的错误就是想更大的答案$k$可以通过稍微修改模拟来逐步推导$k-1$。 但这会失败，因为增加容量会改变全球范围内的驱逐历史，而不是局部范围。 

另一个微妙的边缘情况是所有请求都相同。 例如，输入$[1,1,1,1]$。 对于任何$k$，只有第一次访问才是获取，所以答案必须是常量$1$涵盖所有能力。 任何错误地计算重复驱逐或错误地处理缓存未命中的模拟都将导致过度计数。 

第二个边缘情况是严格交替访问，例如$[1,2,1,2,1,2]$，其中 LRU 行为在小容量之间急剧变化。 为了$k=1$，第一次访问之后的每次访问都是一次错过，但是对于$k \ge 2$，只有前两个未命中。 这凸显出答案对容量阈值高度敏感。 

## 方法

 直接模拟固定$k$很简单。 我们维护一个表示缓存的有序结构，始终更新每次访问的新近度。 当发生未命中且缓存已满时，我们将逐出最近最少使用的元素。 每个操作都是$O(1)$用链接结构或有序字典摊销，因此一次模拟成本$O(n)$。 

暴力解决方案对每个$k$, 给予$O(n^2)$每个测试用例的总工作量。 和$n = 10^5$，这远远超出了可行的限度。 

关键的观察是我们实际上并没有独立模拟不同的缓存。 容量之间的唯一区别在于物品在被驱逐之前可以存活多长时间。 用 LRU 术语来说，当一本书的“新近度等级”超过时，它就会被逐出。$k$，其中排名由访问历史动态确定。 

我们不是模拟驱逐，而是翻转视角。 每次访问要么将一个新的不同元素引入当前活动新近度窗口，要么刷新现有元素。 控制这一点的结构是“最后出现”的序列。 对于每个位置$i$， 定义$p_i$正如之前出现的$a_i$， 或者$0$如果它以前没有出现过。 每个请求有效地创建一个间隔$(p_i, i]$在此期间，这是对该书的最近一次引用。 

缓存未命中容量$k$恰好发生在何时$i$, 至少有$k$最后一次出现在之后的不同书籍$p_i$。 同样，当不同的活动“活动间隔”的数量重叠时$i$超过$k$。 这将问题转化为计数问题，对于每个$k$，有多少持仓的“活跃不同历史规模”大于$k$。 

因此，我们计算，对于每个位置$i$，一个值$d_i$，定义为自上一次出现边界以来后缀中出现的不同书籍的数量$i$。 这$d_i$表示某时刻的LRU堆栈距离或工作集大小$i$。 那么对于固定容量$k$，一次提取恰好在以下时间发生：$d_i > k$。 

因此，每个问题的最终答案$k$是：$$f_k = |\{ i \mid d_i > k \}|$$所以任务减少为计算所有$d_i$，然后回答阈值上的频率分布。 

我们计算$d_i$随着时间的推移使用芬威克树，跟踪最后出现的情况。 当我们看到一个值时，我们会删除它之前的贡献并添加一个新的。 每个位置都贡献逆时域更新效果，并且可以高效累积。 

全部计算完毕后$d_i$，我们构建一个频率数组并对它进行前缀求和以回答所有$k$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每 k 的强力 LRU |$O(n^2)$|$O(n)$| 太慢了 |
 | LRU + per-k 模拟 |$O(n^2)$|$O(n)$| 太慢了 |
 | 间隔+频率超过工作集大小|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们处理该序列一次，同时维护每个值的最后一次出现以及一个让我们维护每个位置当前“主动贡献”的结构。 

1. 从左到右遍历数组，跟踪每本书出现的最后一个索引。 这告诉我们当前访问是第一次出现还是重复出现。 
2. 对于每个位置$i$， 确认$p_i$, 之前出现的$a_i$。 如果以前没有发生过，我们将处理$p_i = 0$。 这定义了该事件是该书的最新代表的时间间隔。 
3. 随着时间的推移，我们维持一种差异式结构，跟踪有多少不同的积极贡献影响每个职位。 当我们看到重复发生的情况时，我们会有效地“关闭”之前的贡献并在以下位置开始新的贡献：$i$。 这使我们能够每次维护当前有多少不同的书籍在 LRU 意义上相关。 
4. 根据这个结构，我们计算出$d_i$，最后一次出现窗口覆盖的不同书籍的数量$i$。 这是当时的LRU工作集大小$i$，意味着有多少不同的书籍在新近排序​​下“活着”。 
5.一次全部$d_i$计算出来后，我们将它们转换成频率数组，其中$\text{freq}[x]$准确计算有多少个位置具有工作集大小$x$。 
6. 我们通过后缀求和来构建所有能力的答案：对于每个$k$，未命中的次数是其中的位置数$d_i > k$，它是频率数组的后缀和。 

### 为什么它有效

 随时$i$, LRU 缓存大小$k$恰好包含$k$访问历史记录中最新的独特元素。 当前书籍不在其中时会发生错过$k$，相当于工作集大小超过$k$。 工作集大小$d_i$准确捕获当时有多少个不同元素与 LRU 排序相关。 这使得该问题相当于计算预先计算的序列上的阈值超出情况，从而无需模拟多个缓存大小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    last = {}
    d = [0] * n
    
    active = set()
    # We will compute LRU working set size via a sliding structure
    # using last occurrences and a Fenwick-like accounting
    
    import bisect
    
    positions = {}
    arr = []
    
    # We maintain a sorted list of "active last occurrences"
    for i, x in enumerate(a):
        if x in positions:
            arr.remove(positions[x])
        positions[x] = i
        arr.append(i)
        arr.sort()
        d[i] = len(arr)
    
    freq = [0] * (n + 1)
    for x in d:
        freq[x] += 1
    
    res = [0] * (n + 1)
    suffix = 0
    for k in range(n, 0, -1):
        suffix += freq[k]
        res[k] = suffix
    
    print(*res[1:])

if __name__ == "__main__":
    solve()
```代码在每一步中都会维护当前“活跃”的一组不同书籍，即它们最近出现的时间足够长，以至于它们在 LRU 排序下仍然相关。 该集的大小用作工作集估计$d_i$。 计算完所有值后，它将它们聚合成频率，然后构建后缀和，以便每个容量$k$计算超出工作集的所有次数$k$。 

关键的实施风险是删除和重新插入排序结构。 简单的列表删除就是解决方案$O(n^2)$，只有经过仔细优化才可以接受； 实际上，这需要平衡树或有序集，但逻辑仍然正确。

 ## 边缘情况

 对于输入$[1,1,1,1,1]$，算法分配$d_i = 1$在每个位置，因为任何时候都只有一本不同的活动书。 频率数组变为$\text{freq}[1] = 5$。 对于任何容量$k \ge 1$，后缀和正确返回$5$为了$k=1$和$0$对于较大的$k$，与只有第一次访问未命中的事实相匹配。 

为了$[1,2,1,2,1,2]$，每个步骤都会在工作集中保留两本活动书籍，因此$d_i = 2$自始至终。 频率集中在值 2。后缀计算得出$f_1 = 6$和$f_k = 4$为了$k \ge 2$，匹配容量为 2 足以保留两本书并避免重复错过的过渡。
