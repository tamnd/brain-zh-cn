 ## 解决方案
 ## 问题理解

 我们正在开发一个虚构的日历系统，其中时间是完全规则的。 每年正好有 12 个月，每个月正好有 30 天，周从周一到周五以固定周期每 5 天重复一次。 

对于每个测试用例，我们在此日历中给出了两个日期。 第一次约会是在已知的工作日进行的。 第二个日期没有附加工作日，任务是使用第一个日期的信息作为参考点来确定第二个日期属于哪个工作日。 

所以从概念上讲，这是一个一维时间轴上的相对偏移问题。 每个日期都可以转换为绝对日索引，并且工作日进展仅取决于两个时间点相隔多少天。 

约束允许年份值大至 10^9，但日历的结构是完全统一的。 这消除了数年或数月的模拟需求。 当年份之间的差距达到数十亿时，任何在日期之间逐日迭代的方法都立即变得不可行，因为单个测试用例可能需要多达 10^9 次操作。 

唯一有意义的边缘情况来自符号处理和模算术。 一个常见的错误是当第二个日期早于第一个日期时错误地计算日期之间的负偏移量。 另一个问题是在 5 天工作日周期中处理不当，特别是当差异为负数或正好被 5 整除时。 

例如，如果今天是 2019-05-12 的星期一，而我们请求 2019-05-11，则答案应该是现实世界中的星期日，但这里的周期只有五天，因此它包含在该限制集中。 如果我们在没有标准化负值的情况下错误地计算模数，我们可能会落在工作日列表之外或错误地对其进行索引。 

另一个微妙的情况是两个日期相同。 那么偏移量为零，并且无论任何计算路径如何，答案都必须恰好是给定的工作日。 

## 方法

 暴力方法可以通过在更新月份和年份转换时重复添加 1 天，将两个日期转换为天数。 每个增量也会以循环方式更新工作日。 这很容易实现和纠正，因为它完全按照定义模拟日历。 

然而，最坏的情况下，日期之间的差距可能会非常大，最多可能相差 10^9 年。 由于每年有 360 天，因此在最坏的情况下大约需要 3.6 × 10^11 天。 因此，一次一天地进行模拟是完全不可行的。 

关键的观察结果是日历是完全线性和周期性的。 每个月和年的结构都是恒定的，因此我们可以直接使用算术计算出任何日期的绝对日数。 一旦两个日期都表示为整数日索引，它们之间的差异将直接决定在大小为 5 的周期中移动多少个工作日步数。 

这将问题简化为计算线性变换和模运算。 该结构与将日期映射到一维数轴上相同，其中每一天都是一个单位，并且工作日形成独立于绝对位置的重复循环。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(以天为单位的距离) | O(1) | O(1) | 太慢了 |
 | 最佳| 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们定义一个函数，将任何日期映射到从固定参考开始的绝对日期索引，例如年 0、月 1、日 1。 

1. 使用公式将每个日期转换为绝对天数`(year * 12 * 30) + (month * 30) + day`。 这是可行的，因为每年和每月都有固定的大小，因此不存在不规则的偏移。 
2. 计算差异`delta = index2 - index1`。 这告诉我们我们向前移动了多少天（如果是负数则向后移动了多少天）。 
3. 将给定的工作日字符串转换为整数`[0, 4]`，将星期一映射到 0 到星期五到 4。 
4. 将日差添加到工作日索引中：`new_index = (start_index + delta) % 5`。 
5. 对结果进行归一化以确保其在范围内`[0, 4]`，Python 已经通过整数的取模行为保证了这一点。 
6. 将结果索引转换回对应的工作日字符串并输出。 

### 为什么它有效

 关键的不变量是工作日的进展仅取决于两点之间的天数，而不取决于绝对的日历位置。 由于在大小为 5 的循环中，每一天都会将工作日精确移动一步，因此将日差添加到已知工作日可以保持正确性。 绝对日期转换可确保任何日期对减少到一致的整数差，并且固定周期上的模运算即使对于负偏移量也能保证正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

days = ["Monday", "Tuesday", "Wednesday", "Thursday", "Friday"]
idx = {d: i for i, d in enumerate(days)}

def to_day_number(y, m, d):
    return y * 12 * 30 + (m - 1) * 30 + (d - 1)

T = int(input())
for _ in range(T):
    y1, m1, d1, s = input().split()
    y1 = int(y1); m1 = int(m1); d1 = int(d1)

    y2, m2, d2 = map(int, input().split())

    base = to_day_number(y1, m1, d1)
    target = to_day_number(y2, m2, d2)

    delta = target - base
    start = idx[s]

    ans = (start + delta) % 5
    print(days[ans])
```转换函数`to_day_number`将日历编码为平面时间线。 每年贡献360天，每月贡献30天，因此算法一致并且避免循环。 

工作日索引是使用字典查找计算的。 然后我们将其移动绝对天数的差异。 模运算直接处理 5 天周期内的环绕。 

一个微妙的点是，Python 的负数模在这种情况下仍然会产生正确的非负余数，因此不需要额外的调整。

 ## 边缘情况

 对于相同的日期，例如`2000 1 1 Monday → 2000 1 1`，计算出的增量为零。 该算法产生`(start + 0) % 5`，直接返回原始工作日索引，无需特殊处理即可保持正确性。 

对于向后运动，例如`2000 1 2 Monday → 2000 1 1`，增量为-1。 计算`(0 + (-1)) % 5`在 Python 中正确计算为 4，对应于星期五。 这证实了负模的行为与循环工作日索引一致。 

对于大的向前跳跃，例如`2000 1 1 Monday → 999999999 12 30`，绝对差极大，但只有其模 5 的余数会影响答案。 该转换将整个范围压缩为单个整数差，并且无论大小如何，循环都确保正确性。
