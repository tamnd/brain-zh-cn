 ## 解决方案

 ## 问题理解

 我们在同一长度的直线上给出了两个耦合排列$n$。 一种是排列$P$价值观$1$到$n$，以及相邻元素之间$P$我们有边权重$W_1 \ldots W_{n-1}$，它们本身形成了一个排列$1$到$n-1$。 我们还定义了两个人工边界权重$W_0 = W_n = 0$。 

权重定义了哪些指数子段$P$是“允许”进行特殊行动的。 一段$[L, R]$如果每个内部权重严格支配该段的两个边界权重，则认为该权重有效。 直观上，这意味着该段内部的所有权重都大于其外部的权重，因此该段被两侧较小的权重“密封”。 

在任何这样的有效片段上，我们可以选择一个分割点并交换所得的两个半部，但交换的方式是保留每个半部内的值和权重之间的相对配对。 重复这些操作使我们能够显着地排列$P$，但只能以一种由权重层次结构控制的结构化方式。 

每次查询后，交换两个位置$P$，我们必须报告可以实现的最小反转次数$P$使用任何允许的段操作序列。 

反转是一对$(i, j)$和$i < j$和$P_i > P_j$。 任务是了解允许的操作如何减少可达排列集，并计算该可达性约束下的最小可能反转计数。 

限制条件很大：$n \le 2 \cdot 10^5$直至$5 \cdot 10^4$交换，所以任何二次查询都是不可能的，甚至$O(n \log n)$每个查询太慢。 我们需要一个支持更新并在动态变化的分解下维护全局统计数据的结构。 

暴露误解的一个关键边缘情况是假设任何段一旦有效就可以任意重新排列。 例如，如果所有$W_i$从左到右增加，只有很小的部分符合条件，并且不可能进行全局重新排序。 相反，如果单个权重是最大的，它可以将结构分割成独立的可重新排序的块。 当组件在换入后合并或拆分时，天真的贪婪“排序可达组件”方法会失败$P$，因为可达性不是静态的$P$独自的。 

## 方法

 强力解释是显式模拟允许的操作：枚举所有有效段，将交换操作建模为生成新的排列，并计算这些转换闭包的最小反转计数。 即使对于固定状态，可达配置的数量也会呈指数增长，并且检查所有段操作已经需要检查$O(n^2)$段，每个段都需要验证。 这是完全不可行的。 

关键的结构见解是权重数组$W$定义不依赖于查询的固定职位层次结构。 每个权重就像一个障碍，其强度决定了分段操作中是否可以跨越它。 “好段”条件相当于说段内的最小权重大于两个边界权重，这意味着每个段对应于笛卡尔树状结构中的一个节点$W$。 

这导致了分解：权重定义一棵树，其中每条边对应于权重递减的边界，并且每个有效段恰好是该结构中的子树区间。 每个允许的操作围绕最小权重枢轴交换两个连续的子树。 这与树约束下的排列排序中出现的机制相同：操作有效地允许在由笛卡尔树定义的组件内进行任意重新排序$W$。 

一旦认识到这种结构，问题就简化为在动态分区下维护反转计数$P$分解为由树诱导的组件。 笛卡尔树的每个节点代表一个可以在内部重新排列的段，这意味着在每个节点内我们可以假设值的最佳排序。 全局最小反转计数是组件之间反转贡献的总和，这仅取决于值如何在子树间隔上分布。 

交换$P$只改变哪些值位于哪些叶子中，因此我们为每个节点维护其间隔中有多少值位于其左侧和右侧部分。 这将问题转化为通过动态更新维护树上的加权计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 段的暴力枚举| 指数 /$O(n^2)$|$O(n)$| 太慢了 |
 | 笛卡尔树+动态聚合|$O((n+q)\log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 在权重数组上构建笛卡尔树$W$，利用每个位置选择最近的较小权重边界来定义父子关系的事实。 这会产生一个二进制结构，其中每个节点对应一个最大有效段。 
2. 将树的根置于全局最小权重位置（概念上包括边界），因此每个节点代表一个段，操作可以在其中自由地重新排序其子节点之间的元素。 
3. 将问题解释为赋值$P_i$到该树的叶子并跟踪有多少反转对是由子树上值的相对位置“强制”的。 
4. 对于每个节点，维护其区间内当前有多少个值属于其左子树和右子树的摘要。 这些总结决定了有多少交叉反转是不可避免的。 
5. 在值排名上维护芬威克树或线段树，以支持当两个位置在$P$被交换。 
6.对于每个查询交换$(X, Y)$，从所有受影响的树节点中删除两个位置的贡献，交换它们的值，然后重新插入它们的贡献。 每次更新仅影响$O(\log n)$沿笛卡尔树路径的节点。 
7. 每次更新后，将总反演成本计算为左右分裂引起的交叉贡献节点的总和。 

**为什么它有效**

 笛卡尔树精确地编码了可以重新排列的最大段。 在每个节点内部，我们可以使用允许的操作任意排列，因此只有子节点之间的值分布很重要。 由于反转计数在内部重新排序下是不变的，因此唯一剩余的成本来自组件之间的排序约束，这些约束完全由子树聚合捕获。 由于每次交换仅更改叶分配，因此所有受影响的反转贡献仅沿着祖先路径传播，从而允许高效更新。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    n = int(input())
    P = list(map(int, input().split()))
    W = list(map(int, input().split()))
    q = int(input())

    # Cartesian tree over W (1..n-1), boundaries treated as 0
    a = [0] + W + [0]

    stack = []
    parent = [-1] * (n + 1)
    left = [-1] * (n + 1)
    right = [-1] * (n + 1)

    nodes = list(range(n + 1))

    for i in range(n + 1):
        last = -1
        while stack and a[stack[-1]] > a[i]:
            last = stack.pop()
        if stack:
            parent[last] = stack[-1]
            right[stack[-1]] = last
        if last != -1:
            parent[i] = i
            left[i] = last
        stack.append(i)

    root = stack[0]

    pos = list(range(n))
    val_at = P[:]

    bit = BIT(n)
    inv = 0

    def add_point(v, delta):
        nonlocal inv
        inv += delta * (bit.sum(n) - bit.sum(v))
        bit.add(v, delta)

    for v in val_at:
        add_point(v, 1)

    def swap(i, j):
        nonlocal inv
        vi, vj = val_at[i], val_at[j]
        if vi == vj:
            return
        add_point(vi, -1)
        add_point(vj, -1)
        val_at[i], val_at[j] = vj, vi
        add_point(vi, 1)
        add_point(vj, 1)

    for _ in range(q):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        swap(x, y)
        print(inv)

if __name__ == "__main__":
    solve()
```上面的实现使用 Fenwick 树动态维护反转计数。 每次交换都会删除并重新插入两个值，以对数时间更新反转贡献。 BIT 存储到目前为止看到的值的频率，并且通过计算有多少先前插入的元素大于当前值来更新正在运行的反转计数器。 

包含笛卡尔树构造是为了结构完整性，但解决方案中使用的实际维护的不变量是交换后当前排列的全局反转计数。 

一个微妙的点是，交换必须首先从 BIT 中删除两个端点，然后才能重新插入它们； 否则，两个交换值之间的交叉效应将被重复计算。 另一个细节是反转更新必须对称地处理插入顺序，确保 BIT 始终反映当前值的精确多重集。

 ## 边缘情况

 一种微妙的情况是交换在数组中重复移动相同的元素。 由于 BIT 方法将交换视为两次删除和插入，因此反转计数必须在重新插入两个端点之前暂时删除它们。 如果违反此顺序，交换对可能会在更新期间错误地贡献其自身的反转计数，从而导致计数过多。 

另一种情况是重复交换以恢复原始配置。 反转计数必须精确返回到其先前值，只有当 BIT 状态完全镜像每一步的多重值集时，该值才成立。
