[CF 1361A - 约翰尼和贡献](https://codeforces.com/problemset/problem/1361/A)

 **评分：** 1700
 **标签：** 构造性算法、图、贪心、排序
 **求解时间：** 4m 7s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们得到一个无向图。 每个顶点代表一个博客，每个博客都有一个想要的主题号`t[i]`。 

约翰尼一一写博客。 当他写博客时，他只看已经写过的邻居。 在他们的主题中，他找到未出现的最小正整数，并将该主题精确地分配给当前博客。 

想要的主题已经确定。 我们的任务是找到撰写博客的顺序，以便约翰尼规则为每个顶点准确生成给定的主题。 如果不存在这样的订单，我们必须输出`-1`。 

该图最多包含`5 * 10^5`顶点和`5 * 10^5`边缘。 这些限制立即排除了任何二次方。 甚至`O(n√n)`会不舒服。 由于图本身只包含`O(n + m)`数据，可接受的解决方案应保持接近线性或`O((n + m) log n)`。 

棘手的部分是所需的主题不是任意标签。 它们必须符合约翰尼使用的类似墨西哥的规则。 有主题的顶点`k`必须已经看到了来自的每个主题`1`通过`k - 1`在其先前写入的邻居中，并且它不能看到主题`k`。 

一些边缘情况可以很容易地破坏一个简单的结构。 

考虑具有相同主题的两个相邻顶点：```
2 1
1 2
1 1
```如果其中一个先写，则另一个已经看到主题`1`，所以它也不能接收主题`1`。 正确答案是`-1`。 

考虑一个顶点，其主题是`3`，但它的邻居只有主题`1`和`4`：```
3 2
1 2
1 3
3 1 4
```话题`2`从它的邻域中消失了。 没有排序可以让 Johnny 分配主题`3`到那个顶点。 正确答案是`-1`。 

另一个微妙的情况是当所有必需的较小主题都存在但邻居具有相同主题时：```
3 3
1 2
2 3
1 3
2 1 2
```顶点`1`有话题`2`。 它看到一个有主题的邻居`1`，这很好，但它也有一个有主题的邻居`2`。 当该 topic-2 邻居较早处理时，topic`2`已经存在于书面邻居中，防止墨西哥人被`2`。 实例是不可能的。 

该解决方案必须有效地验证所有这些条件。 

## 方法

 一个蛮力的想法是尝试构建一个订单并重复模拟约翰尼的规则。 对于每个顶点，我们可以检查已经处理的邻居，计算最小的缺失主题，并检查它是否等于所需的值。 

问题是决定下一个顶点是哪个。 探索可能的顺序是指数级的。 即使我们以某种方式修复了顺序，从头开始为每个顶点重新计算 mex 可能需要重复扫描许多邻居，从而导致粗略的结果`O(nm)`在密集的情况下工作。 

关键的观察结果来自于观察如果存在有效订单将会发生什么。 

假设一个顶点有想要的主题`t`。 

让 Johnny 分配主题`t`, 每个主题`1, 2, ..., t-1`必须已经出现在先前写入的邻居中。 由于在写入该顶点之前这些主题必须已经存在，因此必须更早处理所有主题编号较小的顶点。 

这立即表明了唯一有意义的顺序：按照所需主题的升序处理顶点。 共享同一主题的顶点可以以任何相对顺序出现。 

现在考虑一个顶点`v`有主题`t[v]`。 

当所有较小主题的顶点都已被处理时，可见的主题集`v`的邻域必须恰好足以使墨西哥人平等`t[v]`。 

这意味着：

 1. 邻居不能有话题`t[v]`。 
2. 每个主题来自`1`到`t[v]-1`必须出现在其邻居的话题中。 

如果这些条件适用于每个顶点，那么简单地按主题对顶点进行排序就已经给出了有效的写入顺序。 所有具有较小主题的邻居都会被更早处理，所有相同主题的邻居都不存在，并且每个所需的较小主题都存在。 

这将问题从构建复杂的顺序转变为验证每个顶点的局部条件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数或更糟 | 大| 太慢了 |
 | 最佳 | O((n + m) log n) | O((n + m) log n) | O(n + m) | 已接受 |

 ## 算法演练

 1. 阅读图形和每个顶点所需的主题。 
2. 通过增加主题值来创建顶点排序。 

如果存在有效的解决方案，则必须在每个具有较大主题的顶点之前处理具有较小主题的每个顶点。 
3. 按此排序顺序遍历顶点。 
4.对于当前顶点`v`，收集出现在其所有邻居中的主题值集。 

我们只需要主题标签本身，而不是邻居身份。 
5.如果主题`t[v]`出现在邻居话题中，答案是不可能的。 

Johnny 无法接收主题`t[v]`如果该主题已存在于邻居中。 
6. 检查邻居主题数量是否小于`t[v]`等于`t[v] - 1`。 

由于主题是正整数，这意味着每个主题`1, 2, ..., t[v]-1`完全按照要求存在。 

使用一组，因此重复并不重要。 
7. 如果任一检查失败，则输出`-1`。 
8. 如果所有顶点都通过，则按主题递增顺序输出顶点。 

### 为什么它有效

 考虑一个顶点`v`与所需的主题`t`。 

如果存在有效的书写顺序，则来自的每个主题`1`通过`t-1`必须已经出现在先前写入的邻居中`v`。 最后，`v`必须有具有所有这些主题值的邻居。 另外，主题`t`本身不能出现在邻居中，否则最小的缺失主题将大于`t`。 

这些都是必要条件。 

它们也足够了。 通过增加主题对顶点进行排序后，保证每个主题较小的邻居都会被更早处理。 因为每个话题`1..t-1`存在于邻域和主题中`t`不是，已写邻居中最小的缺失主题正是`t`。 因此约翰尼分配了所需的主题。 

由于每个顶点都独立地满足该参数，因此排序顺序对整个图有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    g = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    t = list(map(int, input().split()))

    order = sorted(range(n), key=lambda x: t[x])

    for v in order:
        cur = t[v]

        seen = set()

        for to in g[v]:
            topic = t[to]

            if topic == cur:
                print(-1)
                return

            if topic < cur:
                seen.add(topic)

        if len(seen) != cur - 1:
            print(-1)
            return

    print(*[v + 1 for v in order])

if __name__ == "__main__":
    solve()
```该图存储为邻接列表，因为两者`n`和`m`可以达到`5 * 10^5`。 

排序步骤创建候选者的写作顺序。 这是该解决方案的中心观察：任何有效的订单都必须尊重不断增加的主题值。 

对于每个顶点，只有邻居主题很重要。 套装`seen`存储小于当前主题的不同主题。 重复项将被自动忽略。 

条件```
len(seen) == cur - 1
```之所以有效，是因为每个主题都是积极的。 如果正好有`cur - 1`不同的较小主题，并且所有主题都小于`cur`，它们必须恰好是集合`{1, 2, ..., cur - 1}`。 

检查具有相同主题的邻居至关重要。 如果没有这个测试，诸如两个相邻顶点都被标记的情况`1`会错误地通过。 

不存在整数溢出问题，因为所有值都适合 Python 整数。

 ## 边缘情况

 考虑具有相同主题的相邻顶点。```
2 1
1 2
1 1
```对于顶点`1`，邻居主题集合包含主题`1`，等于它自己的主题。 该算法未通过同主题检查并输出`-1`。 如果省略此检查，实例将错误地显示为有效。 

考虑一个顶点缺少一个所需的较小主题。```
3 2
1 2
1 3
3 1 4
```顶点`1`想要话题`3`。 它的邻居有话题`{1,4}`。 较小邻居主题的集合是`{1}`。 它的大小是`1`， 但`3 - 1 = 2`。 该算法正确地拒绝了该实例，因为主题`2`缺席。 

考虑重复的较小主题。```
4 3
1 2
1 3
1 4
3 1 1 1
```顶点`1`想要话题`3`。 它的邻居贡献话题`{1,1,1}`。 天真的邻居计数可能会错误地认为有足够的较小主题。 该集合删除重复项，只留下`{1}`。 自话题起`2`缺失，算法输出`-1`。 

考虑一个断开连接的图。```
3 0
1 1 1
```每个顶点都想要主题`1`。 每个顶点没有邻居，因此较小主题的集合是空的，并且同主题检查永远不会触发。 所有顶点都通过验证，并且任何排序都是有效的。 该算法输出排序顺序。
