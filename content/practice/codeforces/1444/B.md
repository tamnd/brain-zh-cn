 ## 解决方案
 ## 问题理解

 我们得到一个长度的数组$2n$，我们必须将其元素准确地分成两组$n$每个元素。 将此视为选择哪些位置进入组$p$; 剩余位置自动分组$q$。 

一旦分割确定，两组就会以一种非常具体的方式重新排列：一组按递增顺序排序，另一组按递减顺序排序。 排序后，我们将递增组中的最小元素与递减组中的最大元素配对，将第二小的元素与第二大的元素配对，依此类推。 分裂的成本是这些成对元素的绝对差之和。 

任务不是找到最佳分割，而是考虑每一种可能的分割并对它们的所有成本求和。 由于分割数是$\binom{2n}{n}$，这是一个天文数字，我们显然无法单独评估它们。 

约束条件$n \le 150{,}000$意味着$2n \le 300{,}000$。 任何比粗略更糟糕的解决方案$O(n \log n)$或者$O(n)$排序后会失败。 这立即排除了子集上的枚举或子集上的任何 DP。 答案的结构必须来自对排序数组的对称性和组合计数。 

一个微妙的边缘情况是所有元素都相等。 在这种情况下，每个分区的成本为零。 尝试在没有仔细配对逻辑的情况下计算差异的简单方法可能会由于不匹配的排序假设而错误地引入非零贡献。 

当值高度不同时，就会出现另一种边缘情况。 成本仅取决于排序后值在两半之间的分配方式，而不取决于原始位置，因此任何意外保留索引结构的解决方案都会过度计数或错误计数。 

## 方法

 暴力方法会枚举所有选择方法$n$元素为$p$，然后对两组进行排序，计算成本并累加。 根据定义，这是正确的，但需要评估$\binom{2n}{n}$案例，其顺序为$10^{90,000}$对于大$n$，完全不可行。 

关键的观察结果是，对整个数组进行排序揭示了隐藏的对称性。 对全数组进行排序后，任意分区对应选择$n$来自排序多重集的元素。 成本结构仅取决于相对排名，而不取决于原始位置。 

考虑配对的一种更结构化的方法是：对整个数组进行排序之后$a$，想象一下我们决定哪些位置进入$p$。 该选择决定哪些值成为下半部分，哪些值成为上半部分。 排序的配对总是匹配极值，因此值的贡献取决于它最终与所有分区中较大或较小元素配对的频率。 

这将问题从枚举分区转移到计算所有子集的预期贡献，乘以子集的数量。 每个元素的角色都变得组合起来：它出现在与更大或更小的物体配对的位置有多少次？ 

最后的见解是，排序后，可以使用有多少子集将某些数字放置在配对边界的每一侧的组合计数来本地计算每个元素的贡献。 这导致使用预先计算的二项式系数和配对的两半之间的对称性对排序元素进行线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(\binom{2n}{n} \cdot n \log n)$|$O(n)$| 太慢了 |
 | 排序数组上的组合计数 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 对数组进行排序$a$按非递减顺序。 这消除了对原始指数的依赖，并确保我们可以纯粹地推理价值排名。 
2. 预先计算阶乘和逆阶乘$2n$。 这允许计算二项式系数模$998244353$在恒定的时间内。 
3. 预先计算所有二项式系数$\binom{n}{k}$隐式地通过阶乘，因为每个组合项都将涉及选择大小的子集$n$。 
4. 将配对结构解释为匹配$i$- 一个子集中的第一个最小元素$i$- 另一个子集中最大的。 这将绝对差异转换为订单统计数据的比较。 
5.固定位置的值$i$并分析其贡献。 为了与较大的元素配对，它必须出现在一个子集中，同时足够的较大元素以相反的顺序填充相反的一侧。 
6. 计算到底有多少个分区$k$第一个元素$i$元素归入同一子集。 这确定当前元素是位于配对的“下”还是“上”侧。 
7. 所有职位的贡献总额。 每个元素贡献一个项，该项与它与较大元素和较小元素匹配的频率成正比，并按实现该配置的有效分区的数量进行加权。 
8. 将所有贡献求模$998244353$。 

关键的组合简化是每个有效分区在排序位置上对称地贡献，因此我们不是明确地跟踪子集，而是跟踪每个排名参与交叉配对的频率。 

### 为什么它有效

 排序结构确保配对始终匹配相反的极端，因此分区的身份仅通过将每个前缀的多少元素分配给每个子集来确定。 这将问题简化为对前缀分割的配置进行计数，并且这些计数是纯二项式的。 产生相同分割模式的每种排列都有相同的贡献，因此按等级分组可以保持正确性并避免计数过多。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    a.sort()
    
    N = 2 * n

    fact = [1] * (N + 1)
    for i in range(1, N + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (N + 1)
    invfact[N] = pow(fact[N], MOD - 2, MOD)
    for i in range(N, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(nr, r):
        if r < 0 or r > nr:
            return 0
        return fact[nr] * invfact[r] % MOD * invfact[nr - r] % MOD

    total = 0

    for i in range(n):
        left = i
        right = N - i - 1

        ways_left = C(i, n - 1) if n - 1 <= i else 0
        ways_right = C(right, n) if n <= right else 0

        contrib = (ways_left * ways_right) % MOD

        total = (total + contrib) % MOD

    print(total)

if __name__ == "__main__":
    solve()
```实现首先对数组进行排序，因为所有有意义的结构都来自相对顺序而不是原始索引。 阶乘和逆阶乘数组允许快速计算二项式系数，这些系数被重复用于计算有多少子集将元素放置在分割的每一侧。 

对于每个位置，代码计算我们可以选择子集的剩余元素的方式有多少种，以便当前元素参与有效的配对配置。 左右组合项对应于从排序数组的前缀和后缀中选择多少个元素。 

这两个计数的乘积反映了由于固定职位角色而引起的分区分裂双方的独立选择。

 ## 边缘情况

 当所有元素都相同时，每个配对都会产生零差异，因为每个$x_i$等于每个$y_i$。 组合机器仍然对分区进行计数，但每个分区的贡献为零，因此在没有特殊情况下总和保持为零。 

当值严格增加时，每个分区都会最大化两半之间的对比度。 该算法处理此问题是因为贡献仅取决于排序数组中的排名位置，因此极值自然会累积更大的组合权重，而无需任何额外的逻辑。 

什么时候$n=1$，该公式减少为两个单例分区。 该算法减少到每个元素的单个组合贡献，匹配两个方向上绝对差的直接定义。
