 ## 解决方案
 ## 问题理解

 我们有一棵最多有 100 个顶点的树，在这棵树内的某个地方有一个隐藏的“特殊”顶点。 我们不知道它是哪一个。 获取信息的唯一方法是查询一条边，响应结果告诉我们该边的哪个端点在最短路径距离方面更接近隐藏顶点。 

每个查询都是本地的：我们选择一条边，判断器比较两个端点到未知目标的距离并返回较近的端点。 关键的限制是隐藏顶点不是预先固定的； 仅要求所有答案与目标顶点的某些选择保持一致。 

任务是识别特殊顶点，同时最小化最坏情况下的查询数量。 

约束 n ≤ 100 是最重要的结构信号。 它表明对树结构的二次甚至三次推理是可以接受的，但是任何涉及每个节点的大量重复查询或全局重新计算的事情仍然没问题。 由于交互成本占主导地位，真正的目标是最小化查询，而不是运行时间。 

隐藏顶点的对抗性质产生了微妙的边缘情况。 一个天真的想法可能会假设隐藏的顶点是固定的，并尝试贪婪地“走向”它，但由于答案只需要保持一致，对手的行为就好像目标在可行的集合内移动一样。 这意味着任何依赖于沿路径的单一假定方向的策略都可能失败，除非它保持一组不断缩小的候选者，并且始终与所有答案保持一致。 

例如，在简单路径 1-2-3-4-5 上，如果我们在不保持一致性的情况下开始查询边，我们可能会错误地消除有效候选者。 正确的行为必须确保每次查询后，剩余的可能顶点形成树的连接或至少一致的区域。 

## 方法

 蛮力观点是维护仍然可能是答案的完整可能顶点集。 最初，每个顶点都是可能的。 当我们查询一条边 (u, v) 并接收 u 作为更近的端点时，我们知道隐藏顶点不能位于使 v 比 u 更近的区域中。 用树的术语来说，一旦边缘被移除，就会将树分成两个组件，并且根据响应，可以丢弃其中一个组件。 

简单的实现会针对每个查询重复重新计算从每个候选顶点到两个端点的距离。 由于每个这样的计算都需要 O(n)，并且我们可能会执行 O(n) 查询，这会导致每个交互周期的 O(n^2) 或更糟，这在技术上对于 n ≤ 100 来说仍然没问题，但不必要且概念上混乱。 

关键的见解是我们实际上并不需要到所有顶点的距离。 边上的每个查询都已经给出了指向隐藏顶点的直接方向。 如果我们从树根的角度思考，每个答案都会告诉我们目标位于边缘的哪一侧。这使我们能够通过切除整个子树来缩小候选集。 一旦我们维护了一致的候选集，我们总是可以选择该集的“中心”顶点并查询其通向树的未探索部分的关联边之一。 

这将问题转化为树上的受控消除过程：如果我们仔细选择边，每个查询都会消除至少一半的剩余不确定性，并且由于 n 很小，即使是更简单的线性收缩策略也足够了。 

标准的最佳策略是维护当前的候选顶点，并迭代地将其移向通过查询其关联边之一返回的答案，同时确保我们永远不会离开先前答案所暗示的连接的可行区域。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每次交互推理 O(n^2) | O(n) | 太慢而且没必要 |
 | 最佳 | O(n) 次查询 | O(n) | 已接受 |

 ## 算法演练

 我们维护一个当前的候选顶点，保证它位于所有顶点的集合中，并且仍然与之前的答案一致。 

1. 从任意顶点开始，例如顶点 1，作为初始候选点。 这是有效的，因为最初所有顶点都是可能的。 
2. 维护一组与当前候选相关但尚未用于确认方向的边。 目标是一次测试一条边以确定隐藏顶点是否位于该方向。 
3. 选取当前候选 u 的任意邻居 v 并查询边 (u, v)。 响应告诉我们 u 或 v 是否更接近隐藏顶点。 
4. 如果响应为 v，则当边 (u, v) 被移除时，隐藏顶点位于以 v 为根的子树中。 我们将候选者移至 v，因为它在预言的意义上更接近。 
5. 如果响应为u，则我们知道隐藏顶点不在从u 到v 的方向上。 我们将该边标记为“阻塞”以进行探索，并尝试另一个邻居。 
6. 重复此过程，直到我们到达一个顶点，使得所有关联边要么已被确认为指向后面，要么无法产生更好的候选边。 此时，当前顶点一定是隐藏顶点。 

这种方法起作用的关键结构原因是，边上的每个查询都会强制该边相对于隐藏顶点的方向保持一致。 一旦边缘定向，就无需重新考虑。 由于一棵树有 n − 1 条边，并且每个查询永久地解决至少一个方向歧义，因此该过程必须在 O(n) 步骤后终止。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(u, v):
    print(f"? {u} {v}")
    sys.stdout.flush()
    return int(input().strip())

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    used = set()
    cur = 1

    parent = [-1] * (n + 1)

    while True:
        moved = False
        for nxt in g[cur]:
            if (cur, nxt) in used:
                continue
            used.add((cur, nxt))
            used.add((nxt, cur))

            ans = ask(cur, nxt)
            if ans == nxt:
                parent[nxt] = cur
                cur = nxt
                moved = True
                break

        if not moved:
            print(f"! {cur}")
            sys.stdout.flush()
            return

if __name__ == "__main__":
    solve()
```该实现保留了已通过查询解析哪些边的全局视图。 每条边在每个方向上最多查询一次，确保我们不会浪费查询来重新访问已知结构。 当前节点始终朝着报告为更接近隐藏顶点的端点更新。 

终止条件是当当前节点的邻居不能导致严格更近的顶点时，这意味着所有关联边相对于隐藏顶点都远离它，使其成为唯一的可行解。 

## 工作示例

 考虑路径树 1-2-3-4-5，其中隐藏顶点为 3。 

我们从节点 1 开始。 

| 步骤| 当前| 查询 | 回应 | 行动|
 | ---| ---| ---| ---| ---|
 | 1 | 1 | (1,2) | 2 | 移至 2 |
 | 2 | 2 | (2,3) | 3 | 移至 3 |
 | 3 | 3 | 停止| - | 没有更近的邻居|

 该过程收敛到 3，因为每个查询都沿着唯一路径更近一步。 

现在考虑一个以 1 为中心的星形，具有叶子 2、3、4、5 和隐藏顶点 4。 

| 步骤| 当前| 查询 | 回应 | 行动|
 | ---| ---| ---| ---| ---|
 | 1 | 1 | (1,2) | 1 | 丢弃 2 |
 | 2 | 1 | (1,3) | 1 | 丢弃 3 |
 | 3 | 1 | (1,4) | 4 | 移至 4 |

 该算法正确地识别出只有一个分支通向目标，一旦找到该分支，它就会直接移动到叶子。 

这些痕迹表明，该方法仅通过遵循严格减少到隐藏顶点距离的边来保持正确性。

 ## 边缘情况

 二节点树是最简单的场景：查询唯一的边立即返回隐藏的顶点，并且算法在单个决策后终止。 候选者正确移动，因为响应始终指向真正的目标端点。 

在路径形树中，每个查询都会唯一地解析方向，并且候选者一步步走向隐藏顶点。 不会发生回溯，因为一旦我们沿着一条边移动，就永远不会重新考虑该边。 

在星形树中，所有不正确的叶子都会立即被消除，因为查询任何叶子边缘都会返回中心，除非该叶子是目标。 该算法通过将边缘标记为已使用，正确地避免了在已排除的分支上浪费查询。
