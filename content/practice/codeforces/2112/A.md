 ## 解决方案
 ## 问题理解

 在这个问题中，爱丽丝和鲍勃正在争夺一个奖品，该奖品将出现在一维线上的两个不同点之一。 爱丽丝已经选择了她的起点`a`。 Bob想要选择一个整数起点`b`与Alice的不同，这样无论两个地点中的哪一个，他都能比Alice更快地到达奖品`x`或者`y`奖品出现。 任意两点之间的距离就是它们坐标的绝对差。 

输入给出多个测试用例，每个测试用例指定`a`,`x`， 和`y`，1 到 100 之间的所有不同整数。输出必须说明每个测试用例是否存在这样的点`b`存在。 如果无论奖品位置如何，鲍勃都可以保证击败爱丽丝，则答案为“是”，否则答案为“否”。 

考虑到严格的界限（所有数字 ≤ 100 且最多 1000 个测试用例），任何迭代可行范围内的所有整数的算法都是可以接受的，因为每个测试用例最多需要 100 个步骤。 但是，无需完全强力枚举即可推理该问题。 

例如，当奖品位置横跨 Alice 的位置时，就会出现主要的边缘情况`a = 3, x = 1, y = 5`。 在这种情况下，如果鲍勃选择一个点来击败爱丽丝获得一个奖品，他可能会在另一个奖品上输给她。 当不存在这样的保证位置时，在不检查两个距离的情况下选择中点或其中一个奖品的天真的方法可能会错误地声明“是”。 

## 方法

 一种简单的暴力方法是检查每个可能的整数`b`1 到 100 之间（不包括`a`）并看看对于两个奖项位置是否，`|b - x| < |a - x|`和`|b - y| < |a - y|`抓住。 这是可行的，因为域很小，并且对于每个测试用例，最多需要 99 次检查，每次检查有两个绝对差异，这在实践中可以忽略不计。 蛮力之所以有效，是因为我们明确验证了鲍勃对于每个可行起始位置的获胜条件，但它有点不优雅。 

最佳解决方案的关键见解是整数`b`保证胜利必须严格限制在`a`以及“最远”的奖品位置。 如果两个奖品都在 Alice 的同一侧（例如`a < x < y`），鲍勃可以从更远的奖品开始，比爱丽丝更接近它，​​这保证了他将击败她获得这两个奖品。 如果奖品位于爱丽丝的两侧（`x < a < y`），无论 Bob 从哪里开始，他都会比 Alice 更接近一个奖品，但距离另一个奖品更远。 因此，只有当两个奖品都在 Alice 的同一侧时，才存在有保证的位置。 这将问题简化为比较位置：鲍勃获胜，如果`(x - a) * (y - a) > 0`。

 | 最佳 | O(t) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 这决定了我们需要评估多少个单独的比赛。 
2. 对于每个测试用例，读取整数`a`,`x`， 和`y`。 这些定义了爱丽丝的起始位置和两个可能的奖品位置。 
3. 计算乘积`(x - a) * (y - a)`。 该产品捕获奖品相对于 Alice 的相对位置。 如果乘积为正，则两个奖品都在爱丽丝的同一侧。 如果为负，则它们位于相反的两侧。 
4. 如果乘积为正，则输出“YES”。 鲍勃可以选择最接近较远奖品的位置，并保证在这两个位置上都击败爱丽丝。 
5. 否则，输出“NO”。 对于鲍勃来说，没有一个单一的整数起始位置可以保证他比爱丽丝更接近这两个奖项。 

为什么它有效：不变的是`(x - a) * (y - a)`完全编码几何排列。 正数意味着两个奖品都在 Alice 的左边或右边，确保存在一个起点来更快地到达这两个奖品。 负数意味着他们骑在爱丽丝身上，使得鲍勃不可能同时选择一个更接近两个奖品的位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, x, y = map(int, input().split())
    if (x - a) * (y - a) > 0:
        print("YES")
    else:
        print("NO")
```代码首先读取测试用例的数量。 对于每个测试用例，它解析代表 Alice 起点和两个潜在奖品位置的三个整数。 核心逻辑检查两个奖品相对于使用该产品的 Alice 是否位于同一侧`(x - a) * (y - a)`。 默认情况下，输出是立即的且不区分大小写，因为 Codeforces 接受“YES”/“NO”。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(sys.stdin.readline())
    for _ in range(t):
        a, x, y = map(int, sys.stdin.readline().split())
        if (x - a) * (y - a) > 0:
            output.append("YES")
        else:
            output.append("NO")
    return "\n".join(output)

# Provided samples
assert run("3\n1 3 4\n5 3 1\n3 1 5\n") == "YES\nYES\nNO", "sample 1"

# Custom cases
assert run("2\n2 3 4\n2 1 3\n") == "YES\nNO", "prizes on same side vs opposite side"
assert run("1\n50 51 52\n") == "YES", "consecutive numbers, all on one side"
assert run("1\n50 49 48\n") == "YES", "consecutive numbers on the other side"
assert run("1\n50 49 51\n") == "NO", "prizes straddle Alice"
assert run("1\n1 2 100\n") == "NO", "extreme values, straddling"

 ## 边缘情况

 如果 Alice 介于两个奖品之间，比如`a = 3, x = 1, y = 5`，产品`(x - a) * (y - a) = (-2) * 2 = -4`是负数。 该算法立即输出“NO”，正确地反映了没有一个位置可以击败爱丽丝获得两个奖项。 如果两个奖品都在爱丽丝的右边（`a = 1, x = 3, y = 4`），乘积为正，算法输出“YES”，正确地允许鲍勃选择`b = 4`以保证胜利。 这些案例表明，产品测试可以稳健地处理跨界和单向奖励配置。
