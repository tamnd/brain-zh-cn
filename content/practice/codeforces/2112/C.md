 ## 解决方案
 ## 问题理解

 给定一个已排序的整数数组，我们需要计算 Alice 可以选择三个不同索引的方式有多少种，这样无论 Bob 之后做什么，Alice 选择的三元组都是“安全的”。 

事件的顺序很重要。 Alice 首先选择三个元素。 然后鲍勃选择数组中的任何一个位置并将其涂成蓝色。 如果鲍勃碰巧选择了爱丽丝的红色元素之一，则该元素将停止对红色总和做出贡献，因为它被覆盖。 仅当剩余红色元素的总和严格大于 Bob 选择的元素的值时，Alice 才会获胜。 

“无论鲍勃的行为如何”这句话意味着我们必须在看到爱丽丝的三元组后强制鲍勃做出最坏的选择。 因此，对于每个选择的三元组，我们必须考虑两种可能性：鲍勃在三元组内部或外部进行选择，并且在这两种情况下，爱丽丝仍然必须获胜。 

约束足够严格，以至于三元组的三次枚举太大。 和$n$每次测试最多 5000 个，总计最多 5000 个，这是一个天真的做法$O(n^3)$方法的顺序是$10^{11}$操作，远远超出了限制。 甚至一个$O(n^2 \log n)$每个测试的方法都是临界的，所以我们应该期望$O(n^2)$或者$O(n \log n)$解决方案。 

当许多值相等时，会出现微妙的边缘情况。 例如，如果所有元素都相同，爱丽丝可能会认为任何三元组都有效，因为总和很大，但鲍勃总是可以选择红色元素并显着减少有效总和，这可以使不等式无效。 另一个棘手的情况是当最大元素与其他元素相比非常大时，因为鲍勃将始终以该值为目标，除非即使在丢失一个红色元素后，红色总和仍占主导地位。 

## 方法

 直接的暴力解决方案将迭代所有三元组$i < j < k$，计算总和$S = a_i + a_j + a_k$，然后模拟鲍勃的最佳反应。 

鲍勃有两个有意义的策略。 如果他选择一个非红色元素$x$，爱丽丝的红和保持不变$S$，所以我们需要$S > x$。 最糟糕的选择是三元组之外的最大元素。 如果他选择了红色元素$a_t$，红色总和变为$S - a_t$，鲍勃将其与$a_t$，所以我们需要$S - a_t > a_t$， IE。$S > 2a_t$。 由于鲍勃会选择最差的红色元素，所以这就变成了$S > 2 \cdot \max(a_i, a_j, a_k)$。 

因此，对于固定三元组，条件简化为两个不等式：

 1.$a_i + a_j + a_k > \max(a)$在整个数组中
 2.$a_i + a_j + a_k > 2 \cdot a_k$（因为数组已排序并且$a_k$三重中最大的）

 暴力检查所有三元组并在恒定时间内验证这两个条件，但这是$O(n^3)$。 

关键的简化是修复三元组中的最大元素，例如$a_k$，并将问题简化为计数对$(i, j)$和$i < j < k$满足线性不等式。 这立即表明了对排序数组的两指针策略。 

对于每个$k$，我们想要：$$a_i + a_j > \max(2a_k, a_k + a_{\text{max outside}} - a_k)$$由于数组是全局排序的，全局最大值主导外部情况，因此我们对其进行预先处理并将条件减少到一个简单的阈值，其中涉及$a_k$。 

这减少了对带有两个指针的扫描对的计数$O(n)$每$k$，导致$O(n^2)$全部的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$|$O(1)$| 太慢了 |
 | 最优两指针 |$O(n^2)$|$O(1)$| 已接受 |

 ## 算法演练

 我们依赖于数组已排序的事实，这使我们能够清楚地推断最大值并有效地对对进行计数。 

1.固定三元组中最大的元素作为索引$k$。 我们对待$a_k$作为第三个选择的元素。 
2. For this$k$，设置两个指针：$i = 0$,$j = k - 1$。 
3.我们尝试先选择两个元素$k$这样它们的总和就足以满足 Bob 的两个约束。 所需的阈值变为：$$a_i + a_j > \max(2a_k, a_k + a_{\max})$$自从$a_{\max}$每个测试用例都是固定的，这成为所有测试用例的恒定阈值$k$。 
4. 虽然$i < j$， 如果$a_i + a_j$足够大，那么每对$(i, i+1, ..., j-1, j)$有固定的$j$和变化的$i$向下可能有所贡献。 我们计算所有以以下结尾的有效对$j$，然后移动$j$左边。 
5. 否则，总和太小，所以我们增加$i$来扩大总和。 
6. 累积所有有效对$k$。 

关键的设计选择始终是锚定三重中最大的元素。 这将三维计数问题分解为二维计数问题，其中排序数组的单调性允许线性扫描。 

### 为什么它有效

 对于任何有效的三元组，最大的元素必须是某个$a_k$。 一次$k$是固定的，所有剩余的约束仅取决于索引的对和$< k$。 因为数组是有序的，递增$i$增加总和，并减少$j$减少它，给出一个单调结构，保证两个指针恰好探索所有有效对一次。 不会跳过任何有效对，并且不会对无效对进行计数，因为每个计数对都明确满足导出的阈值条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        mx = a[-1]
        ans = 0
        
        # fix k as largest element of triple
        for k in range(2, n):
            target = max(2 * a[k], mx)
            
            i, j = 0, k - 1
            while i < j:
                if a[i] + a[j] > target:
                    ans += (j - i)
                    j -= 1
                else:
                    i += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```该实现修复了三元组的第三个元素并计算其左侧的有效对。 变量`target`编码最坏情况的要求：鲍勃选择数组中最大的元素或销毁一个红色元素，因此我们需要对和加上固定元素来主导这两种情况。 

两个指针循环确保每个有效对在给定的情况下可行时被计数一次`j`。 表达式`ans += (j - i)`有效，因为一旦`a[i] + a[j]`足够大，之间的所有中间索引`i`和`j`配对`j`也将满足排序带来的不等式。

 ## 边缘情况

 当所有值都相等时，每个三元组要么轻微满足阈值，要么轻微违反阈值，具体取决于大小。 该算法可以干净地处理这个问题，因为一旦总和超过固定目标，两个指针总是对所有对进行计数，这种情况是一致发生的。 

对于最小的有效输入$n = 3$，只有一个可能的三元组，算法通过设置正确地评估它$k = 2$并尝试进行单对检查。 如果不等式失败，则不添加任何贡献。 

当末尾有一个非常大的元素时，大多数三元组都会失败，因为$2a_k$支配对和。 该算法自然会拒绝这些，因为`target = max(2*a[k], mx)`变大，迫使两个指针找不到有效的对。
