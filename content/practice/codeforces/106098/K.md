 ## 解决方案
 ## 问题理解

 我们给出了长度的排列$n$，这意味着它包含来自的每个值$0$到$n-1$正好一次。 对于此排列的每个连续段，我们计算其 MEX，即未出现在该段中的最小非负整数。 任务是对所有可能的子数组上的这些 MEX 值求和。 

直接的解释是，每个子数组贡献一个值，具体取决于它已经“覆盖”从零开始的小整数集的程度。 如果子数组包含$0,1,2,\dots,k-1$但失踪了$k$，那么它的 MEX 是$k$。 

输入大小达到$2 \cdot 10^5$每次测试总共，所以任何平方$n$每个测试用例立即不可行。 枚举所有子数组已经花费了$O(n^2)$，并为每个重新计算 MEX 会将其推向$O(n^3)$在一个天真的实现中。 即使维护每个窗口的频率阵列仍然剩下$O(n^2)$工作，这太慢了。 

关键的结构细节是我们正在处理排列。 这会删除重复项并确保每个数字都有唯一的位置。 该属性使得可以全局推理值的贡献，而不是重新计算子数组状态。 

一些边缘情况揭示了天真的思维失败的原因。 

如果排列已经在增加，例如$[0,1,2,3]$，每个前缀的 MEX 等于其下一个缺失值，但许多子数组的 MEX 仍然等于 0，因为它们跳过了早期元素。 单纯的仅使用前缀的方法会错过这些贡献。 

如果把排列颠倒过来，比如$[3,2,1,0]$，大多数子数组都会丢失小值，并且 MEX 经常变为 0 或 1。仅计算值的出现次数而不跟踪子数组覆盖范围会导致计数过度。 

如果$0$出现在接近尾声的地方，例如$[1,2,3,0]$，左侧的许多子数组永远不会看到 0，因此它们的 MEX 为 0，即使它们可能包含其他小值。 任何假设存在小值就足以实现正 MEX 的方法在这里都会失败。 

核心困难在于，MEX 取决于_范围内的不存在_，而不仅仅是存在计数。 

## 方法

 蛮力策略很简单：枚举每个子数组，维护一个频率数组，并通过从 0 向上扫描直到找到缺失值来计算 MEX。 每个子阵列的成本$O(n)$重新计算 MEX，有$O(n^2)$子数组，给出$O(n^3)$在最坏的情况下。 即使使用增量更新，MEX 扫描仍然可以做到$O(n^2)$，这对于$2 \cdot 10^5$。 

观察的关键是倒转观点。 我们不是问“每个子数组的 MEX 是什么”，而是问“对于每个值$k$，有多少个子数组的 MEX 严格大于$k$”。这种转换之所以有效，是因为子数组的 MEX 大于$k$恰好当它包含所有值时$0$通过$k$。 

现在排列结构变得强大了。 对于固定的$k$，子数组包含所有值的条件$0..k$相当于其左端点位于这些值中最早出现的值之前，而其右端点位于这些值中最新出现的值之后。 

这将问题简化为区间覆盖：对于每个$k$，跟踪值的最小和最大位置$0..k$。 跨越该区间的每个子数组都会为所有 MEX 值贡献 1，直到$k$，并且这些贡献可以有效地累积。 

随着我们增加$k$，我们只将间隔延长一个新位置，因此我们可以增量地维护当前的边界段。 

这减少了推理的问题$O(n^2)$子数组对值进行线性扫描$0..n-1$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$或者$O(n^3)$|$O(n)$| 太慢了 |
 | 最佳 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们利用每个值只出现一次的事实，因此我们将其位置存储在数组中`pos`。 

然后，我们维护迄今为止看到的值中的最小和最大索引。 

1. 构建数组`pos[x]`给出价值指数`x`在排列中。 这允许恒定时间访问每个值所在的位置。 
2.初始化两个变量`L`和`R`作为价值的地位`0`。 此时包含所有值的区间$0..0$只是一个点。 
3. 维护一个答案累加器`ans`和一个变量`k`表示区间中包含的当前最大值。 
4. 对于每个下一个值`k`从 1 到$n-1$，通过更新扩大区间`L = min(L, pos[k])`和`R = max(R, pos[k])`。 这使得间隔覆盖了所有出现的情况$0..k$。 
5. 更新区间后，每个完全包含的子数组`[L, R]`包含所有值`0..k`，因此它对所有 MEX 值的贡献至少达到`k`。 这样的子数组的数量是`(L + 1) * (n - R)`。 
6. 将此计数添加到答案贡献值中`k`。 
7. 总捐款额`k`。 最终总和等于所有子数组的 MEX 总和。 

关键思想是每个扩展步骤准确地计算至少有多少个新实现 MEX 的子数组`k`，并且这些层堆叠得很干净。 

### 为什么它有效

 该算法依赖于处理值后的不变量`k`, 段`[L, R]`是包含所有数字的最小区间`0..k`。 任何包含此区间的子数组都必须包含所有这些值，因为在排列中每个值的位置都是唯一的。 相反，任何至少缺少其中一个值的子数组都不能完全覆盖`[L, R]`。 

这在包含所有必需元素的子数组和覆盖固定间隔的子数组之间创建了直接等价。 由于区间包含很容易进行组合计数，因此 MEX 贡献变成了独立增量约束的总和，而不是重叠子阵列状态的总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    p = list(map(int, input().split()))

    pos = [0] * n
    for i, v in enumerate(p):
        pos[v] = i

    L = R = pos[0]
    ans = 0

    for k in range(1, n):
        L = min(L, pos[k])
        R = max(R, pos[k])
        ans += (L + 1) * (n - R)

    print(ans)
```该解决方案首先记录每个数字出现的位置，因为排列保证了唯一性。 间隔`[L, R]`跟踪已包含截至当前的所有值的最小段`k`。 乘法`(L + 1) * (n - R)`计算有多少子数组完全覆盖该段：左端点可以从以下任意位置选择`0`到`L`，以及任意位置的正确端点`R`到`n-1`。 

一个常见的错误是将其解释为对具有 MEX 的子数组进行计数`k`，但它实际上至少计算了那些拥有 MEX 的人`k`。 总而言之`k`是通过标准层分解重建精确的 MEX 总和。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        pos = [0] * n
        for i, v in enumerate(p):
            pos[v] = i

        ans = 0
        for k in range(1, n):
            L = min(L, pos[k])
            R = max(R, pos[k])
            ans += (L + 1) * (n - R)

        out.append(str(ans))
    return "\n".join(out)

 ## 边缘情况

 对于单元素排列，唯一的子数组的 MEX 等于 1，但由于我们只对从 0 开始的值求和，因此算法在处理后正确地生成 0。 该区间永远不会超出一点，因此不会添加任何贡献。 

对于像这样的排序排列`[0,1,2,...]`，区间从左向右逐渐扩大，没有跳跃，每一步都贡献精确`(0+1)*(n-R)`直到最后`R`变成`n-1`。 这符合早期子数组快速累积所有小值的直觉。 

对于反向排列，第一个值`0`是在最右边，所以`L`保持较小的同时`R`很大。 这使得`(L+1)`最小，只有后来的扩展才稍微增加它。 该结构正确地捕获了大多数子数组早期不包含小前缀，从而使大多数范围的 MEX 保持较低。
