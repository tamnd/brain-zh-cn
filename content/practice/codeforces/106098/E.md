 ## 解决方案
 ## 问题理解

 我们得到了一组等边三角形。 边长是不同的偶数，并且每个三角形都保持其原始索引。 

对于每个查询，三个数字$d_1,d_2,d_3$被给予。 这些是距某个内点的垂直距离的平方$P$到等边三角形的三条边。 我们必须确定给定的三角形之一是否可以包含这样的点。 如果可以，我们输出任何匹配三角形的索引。 否则我们输出`-1`。 

输入尺寸很大。 三角形数量和查询数量都可以达到$2 \cdot 10^5$。 任何扫描每个查询的所有三角形的解决方案都需要大约$4 \cdot 10^{10}$在最坏的情况下进行操作，这是完全不可行的。 每个查询必须在大致恒定或对数时间内得到回答。 

棘手的部分是查询提供平方距离，而不是距离本身。 恢复实际距离需要了解平方根之和何时可以等于等边三角形的高。 

一个常见的错误是计算浮点平方根并比较它们。 考虑：```
n = 1
l = [14]

query:
48 3 12
```距离是$4\sqrt3$,$\sqrt3$， 和$2\sqrt3$。 他们的总和是$7\sqrt3$，这正是边长三角形的高$14$。 浮点运算可能会引入舍入误差并错误地拒绝查询。 

另一个微妙的情况是：```
n = 1
l = [12]

query:
3 12 1
```距离是$\sqrt3$,$2\sqrt3$， 和$1$。 它们的总和包含两者$\sqrt3$和一个有理分量。 没有整数倍$\sqrt3$可以等于这个总和，所以答案是`-1`。 仅检查近似数值相等的解决方案可能会失败。 

最后的边缘情况是当距离不是以下形式时$3a^2$:```
n = 1
l = [6]

query:
6 6 6
```每个距离是$\sqrt6$。 总和是$3\sqrt6$，它不能是该问题中任何三角形的高。 正确答案是`-1`。 

## 方法

 最直接的方法是处理每个查询，计算所需的三角形边长，然后扫描所有可用的三角形以查找匹配项。 

几何本身很简单。 在等边三角形中，任意内点到三边的垂直距离之和等于高。 这就是维维亚尼定理。 如果距离是$x_1,x_2,x_3$， 然后$$x_1+x_2+x_3 = h.$$由于边长为$l$,$$h=\frac{\sqrt3}{2}l.$$蛮力的想法可以计算$$\sqrt{d_1}+\sqrt{d_2}+\sqrt{d_3}$$并检查它是否等于任何三角形的高。 即使计算完全正确，扫描所有$n$每个查询的三角形成本$O(nq)$，太大了。 

关键的观察结果来自于每个三角形边长都是偶数这一事实。 

让$l=2k$。 那么海拔高度就变成了$$h=k\sqrt3.$$所以我们需要$$\sqrt{d_1}+\sqrt{d_2}+\sqrt{d_3}=k\sqrt3.$$写每一个$d_i$作为$$d_i=s_i^2 \cdot m_i,$$在哪里$m_i$是无平方的。 然后$$\sqrt{d_i}=s_i\sqrt{m_i}.$$具有不同无平方部分的平方根项与有理数线性无关。 由于每个距离都是正数，因此不可能取消。 它们的总和可以等于纯倍数的唯一方法$\sqrt3$是如果每个项都已经有无平方部分$3$。 

这意味着每一个$d_i$必须完全是$$d_i=3a_i^2.$$然后$$\sqrt{d_i}=a_i\sqrt3,$$和$$\sqrt{d_1}+\sqrt{d_2}+\sqrt{d_3}
=
(a_1+a_2+a_3)\sqrt3.$$因此$$k=a_1+a_2+a_3,
\qquad
l=2k.$$整个查询减少为：

 1. 检查是否每个$d_i/3$是一个完美的正方形。 
2. 对平方根求和。 
3.查找边长$2k$在哈希表中。 

这提供了恒定时间的查询处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nq)$|$O(1)$| 太慢了|
 | 最佳|$O(n+q)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 读取所有三角形边长并存储从边长到其原始索引的映射。 
2. 对于每个查询，独立处理三个值。 
3. 对于一个值$d$，首先检查它是否能被整除$3$。 如果不是，则无法查询。 
4. 计算$x=d/3$。 让$r=\lfloor\sqrt{x}\rfloor$。 
5. 验证$r^2=x$。 如果没有，那么$d$不是以下形式$3a^2$，所以查询是不可能的。 
6. 积累$r$。 这个值正好是$a_i$。 
7. 处理完这三个数字后，让$$k=a_1+a_2+a_3.$$所需边长为$$l=2k.$$1. 检查是否$l$存在于可用三角形的哈希表中。 
2.如果存在则输出存储的索引，否则输出`-1`。 

### 为什么它有效

 对于等边三角形，任意一个内点到三边的垂直距离之和等于高。 边长为偶数的三角形的高$l=2k$是$k\sqrt3$。 

查询仅在以下情况下才有效$$\sqrt{d_1}+\sqrt{d_2}+\sqrt{d_3}$$恰好是$\sqrt3$。 由于所有距离都是正数，因此每个平方根项本身必须是$\sqrt3$。 因此每个$d_i$必须是$3a_i^2$。 

当该条件成立时，高度变为$$(a_1+a_2+a_3)\sqrt3,$$对应边长$$2(a_1+a_2+a_3).$$该算法精确计算该边长并检查它是否存在于给定的三角形中。 没有遗漏有效的三角形，并且每个报告的三角形都满足所需的距离总和。 

## Python 解决方案```python
import sys
from math import isqrt

input = sys.stdin.readline

n, q = map(int, input().split())
lengths = list(map(int, input().split()))

pos = {}
for i, l in enumerate(lengths, start=1):
    pos[l] = i

ans = []

for _ in range(q):
    d1, d2, d3 = map(int, input().split())

    total = 0
    ok = True

    for d in (d1, d2, d3):
        if d % 3 != 0:
            ok = False
            break

        x = d // 3
        r = isqrt(x)

        if r * r != x:
            ok = False
            break

        total += r

    if not ok:
        ans.append("-1")
        continue

    need = 2 * total
    ans.append(str(pos.get(need, -1)))

sys.stdout.write("\n".join(ans))
```第一部分构建一个从边长到索引的哈希表。 由于所有边长都是不同的，因此一个简单的字典就足够了。 

对于每个查询，代码检查每个平方距离是否具有以下形式$3a^2$。 整数平方根的计算方法为`isqrt`，这避免了所有浮点精度问题。 

变量`total`商店$$a_1+a_2+a_3.$$所需边长为`2 * total`。 在字典中查找它给出了$O(1)$回答。 

最常见的实现错误是使用浮点平方根。 值可以大到$10^{18}$，并且精确的相等比较变得不可靠。`isqrt`使用整数执行整个计算。 

另一个容易犯的错误是忘记边长是$2k$， 不是$k$。 等边三角形的高是$\frac{\sqrt3}{2}l$，并求解$l$引入了这个因数二。

 ## 边缘情况

 考虑：```
1 1
6
3 3 1
```该算法检查第三个值。 自从`1 % 3 != 0`，它立即拒绝查询并输出`-1`。 总和包含有理分量，不能等于以下形式的高度$k\sqrt3$。 

考虑：```
1 1
12
6 6 6
```每个值都可以被 3 整除，但是$$6/3 = 2$$不是一个完美的正方形。 整数平方根检查失败，所以答案是`-1`。 这可以防止错误治疗$\sqrt6$作为$\sqrt3$。 

考虑：```
1 1
8
3 12 27
```这些值对应于$a_1=1$,$a_2=2$,$a_3=3$。 他们的总和是$6$，所以所需的边长为$12$。 唯一可用的三角形有边长$8$，因此查找失败并且算法输出`-1`。 

在每种情况下，决策都直接根据距离的精确代数结构得出，不涉及浮点运算。
