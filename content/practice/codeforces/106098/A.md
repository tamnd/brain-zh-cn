 ## 解决方案
 ## 问题理解

 该问题是在一系列问题上进行的两人游戏，其中每个问题都有不同的难度值。 难度值形成一个排列，因此从 1 到 n 的每个数字都恰好出现一次。 

游客先行动，然后玩家轮流行动。 在每个回合中，当前玩家选择任何剩余的问题并立即获得与其难度相等的分数。 然后该问题将从池中删除。 当没有问题时游戏结束，总分较大的玩家获胜。 如果两个分数相等，Tourist 仍然不会明确输掉比赛，但任务要求我们决定在最佳比赛下谁获胜。 

一个关键的观察是，对于任何时候可以解决哪个问题都没有限制，因此唯一的结构来自评分规则和回合顺序。 由于所有价值都是积极且独特的，因此双方玩家总是会在可能的情况下获得较大的剩余价值。 

输入大小高达 100000，这会立即排除任何模拟涉及在二次时间内搜索或重新计算每次移动选择的策略的解决方案。 任何重复检查所有剩余元素的方法都会降级为 O(n^2)，这太慢了。 我们应该期望答案取决于排列的直接组合属性，而不是任何动态模拟。 

当 n 很小时或当排序是对抗性时，会出现微妙的边缘情况。 

例如，当 n = 1 且数组为 [1] 时，Tourist 取唯一元素并获胜。 

当n = 2且数组为[1, 2]时，Tourist取2，Bald取1，Tourist赢1分。 一个天真的想法可能是回合顺序本身就决定了获胜者，但这已经具有误导性，因为最佳游戏总是选择最大的剩余元素。 

更深层次的问题是，任何试图跟踪数组中“位置”的策略都是无关紧要的，因为数组实际上并不具有位置性，只有值的多重集才重要。 

## 方法

 暴力模拟将尝试明确地对游戏状态进行建模。 在每一回合，玩家都会扫描所有剩余的元素，根据某种策略选择一个元素，然后将其删除。 即使两个玩家总是贪婪地选择，我们仍然模拟 n 轮，每轮需要扫描最多 O(n) 个元素，导致 O(n^2) 时间。 对于 n = 100000，这已经失败了。 

重要的简化是认识到两个参与者的能力是对称的并且完全理性，并且每一步都只是对剩余数量的选择。 由于所有值都是不同的且可累加的，因此唯一有意义的决策是使用多组值的顺序。 

如果我们按降序对所有值进行排序，则最佳游戏会有效地将最大的剩余值分配给当前玩家。 玩家不会跳过较大的值而采用较小的值，因为这只会减少他们的最终总和，并为对手提供更好的未来位置。 

因此，游戏简化为在游客和秃头之间交替分配排序值。 游客优先选择，然后是秃头，依此类推。 

因此，Tourist 接收排序数组中位置 0、2、4... 的值，而 Bald 接收位置 1、3、5... 的值。 

通过比较这两个子序列的总和来确定获胜者。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n^2) | O(n^2) | O(n) | 太慢了|
 | 排序 + 交替求和 | O(n log n) | O(n log n) | O(1) 额外（除了输入） | 已接受 |

 ## 算法演练

1. 读取大小为 n 的排列并存储所有值。 
2. 按降序对值进行排序，以便我们始终首先考虑剩余的最佳选择。 
3. 初始化两个累加器，一个用于游客，一个用于秃头。 
4. 迭代已排序的数组。 将索引 0、2、4、... 分配给游客，将 1、3、5、... 分配给秃头，将每个值添加到相应的总和中。 
5. 比较两个总和。 如果游客的总数严格更大，他就获胜。 否则秃头获胜。 

关键的推理步骤是为什么交替分配是有效的。 在游戏中的任何时刻，两名玩家都会看到相同的剩余集合。 由于所有值都是正的且独立的，因此在存在较大值的情况下采用较小值永远不会改善结果。 这迫使两个玩家陷入相同的贪婪行为，使得排序后的交替分配代表唯一的最佳结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort(reverse=True)
    
    tourist = 0
    bald = 0
    
    for i, val in enumerate(a):
        if i % 2 == 0:
            tourist += val
        else:
            bald += val
    
    if tourist > bald:
        print("Tourist")
    else:
        print("Bald")

if __name__ == "__main__":
    solve()
```该解决方案首先按降序对数组进行排序，以便始终首先考虑最强的可用选择。 然后，循环纯粹根据回合索引的奇偶性来分配值，这对应于谁先玩并保持严格的交替。 

这里的一个常见错误是尝试使用优先级队列模拟实际的游戏决策，但仍然不必要地重新计算每个回合的选择。 这会导致冗余逻辑而不改变结果。 正确的见解是游戏永远不会偏离全局降序分配。

 ## 边缘情况

 一种重要的边缘情况是 n = 1。`1 1`，游客立即获得唯一的值并获胜。 该算法将索引 0 分配给游客，因此游客正确地获得了全部总和。 

另一种边缘情况是最大值远大于所有其他值的总和，例如`100000 1 2 3 ...`。 排序后，Tourist 总是先取最大的元素，无论剩余分布如何，都保证占主导地位。 交替分配正确地反映了这一点，因为第一个元素始终分配给游客。 

最后一个微妙的情况是当总和非常接近时。 例如`3 2 1`。 排序过程得出Tourist = 3 + 1 和Bald = 2，因此Tourist 仍然获胜。 这证实了基于奇偶校验的分配正确地模拟了最佳行为，即使天真的直觉可能建议采取平衡行动。
