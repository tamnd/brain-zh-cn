 ## 解决方案
 ## 问题理解

 我们得到了排列成一行的 n 只鹅的序列，其中每只鹅都与一个任务类型 ai 相关联。 “计划”是通过选择一段连续的鹅来选择的，这意味着一个区间 [l, r]，并且只有这些鹅参与完成他们的任务。 

鹅选择一个时间间隔后，鸭子就会查看任务位置。 任务位置只是一个值 x，我们计算所选区间内有多少只鹅具有 ai = x。 仅当所选时间间隔中正好有 k 只鹅执行该任务时，鸭子才可以在任务位置伏击。 如果这样的任务在选定的时间间隔内存在，则该计划被认为是危险的。 

目标是计算有多少个区间 [l, r] 不产生区间内频率恰好为 k 的任务值。 

输入大小高达 n = 10^6，因此任何尝试所有 O(n^2) 间隔的解决方案都立即不可行。 由于常量较大和内存局部性问题，即使是 O(n sqrt n) 在最坏的情况下也已经太慢了。 问题的结构强烈表明我们需要将“区间内没有值恰好出现 k 次”的条件转换为所有区间上的全局计数问题。 

当 k = 1 时，会出现微妙的边缘情况。在这种情况下，任何在间隔中只出现一次的值都会变得危险，因此完全由不同元素组成的间隔将变得无效。 仅跟踪重复项的简单方法完全忽略了这一点，因为重复项不是问题，单次出现才是问题。 

另一个边缘情况是所有值都相同。 那么每个长度恰好为 k 的区间都会立即变得危险，因此答案就变成区间总数减去那些特定的区间，但前提是 k 相对于 n 足够小。 

## 方法

 解决该问题的直接方法是枚举所有区间 [l, r]，计算其中所有 ai 的频率，并检查是否有任何频率等于 k。 这可以通过维护频率表同时为每个 l 扩展 r 来完成。 如果我们维护计数，则每个间隔的检查为 O(1)，但每个 r 的更新频率仍然会导致总体 O(n^2) 转换。 当 n 达到 10^6 时，这远远超出了任何限制。 

关键的观察结果是，该条件仅取决于某个值是否恰好在区间内达到频率 k。 我们可以专注于使值变得“危险”的原因，而不是全局跟踪所有频率：如果值 x 在某个区间内出现，并且包含 k 个 x 出现的连续块（​​不一定在索引空间中连续，但在段内按出现顺序连续），则该值在该区间内变得危险。 这建议将数组转换为一个结构，其中每个值的出现都被跟踪，并且我们推断间隔如何捕获相同值的 k 次出现。 

对于每个值 x，考虑其出现位置 pos[x][i]。 如果存在索引 i，使得 pos[x][i] 是 [l, r] 内第 k 个出现的端点，则区间 [l, r] 恰好包含 k 次出现的 x，这意味着：

 pos[x][i] - pos[x][i-k+1] 贡献了一个有效窗口，其中间隔恰好包含 k 次出现，而没有 x 的上一个或下一个出现的干扰。 

换言之，每个值 x 都会生成多个“不良区间约束”，其形式为：

 区间 [pos[x][i-k+1], pos[x][i]] 是一个见证段，不得完全包含在 [l, r] 中，除非它会产生危险情况。 

因此，问题就变成了避免完全包含任何这些禁止的见证片段的计数间隔。 每次出现最多贡献一个这样的片段，因此片段总数为 O(n)。 然后，我们对避免完全包含任何禁止段的间隔进行计数。

我们将问题转化为经典的区间包含排除问题。 对于每个右端点 r，我们维护在某个 l 阈值之后开始的最近的禁止段，并使用扫描线或最后出现的边界结构来计算有多少 l 是有效的。 

更直接的方法是从左到右处理r。 对于每个 r，我们为每个值 x 维护其最后 k 次出现，并为每个 r 维护最早的 l，使某个值恰好位于 [l, r] 内的 k。 这对所有此类“激活点”产生约束 l > min。 然后，对于固定 r 的所有有效 l 形成一个前缀，因此我们可以计算每个 r 的 O(1) 贡献。 

这减少了维护每个值第 k 个最后出现的滑动窗口的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 间隔暴力破解 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 发生窗口+扫描| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们从左到右处理数组，同时维护每个值的出现列表。 

1. 对于每个值 x，存储其最近 k 个出现的队列。 

这让我们知道何时恰好有 k 个事件以当前位置结束。 
2. 处理位置r时，将r追加到a[r]的出现列表中。 

如果列表大小超过 k，则删除最旧的列表，因为它不再定义以 r 结尾的 k 窗口。 
3.如果列表大小恰好为k，则由该列表中的第一个和最后一个位置形成的段是候选“坏见证段”。 这意味着，如果区间 [l, r] 完全包含该段，则 x 在其中至少出现 k 次，以 r 结束。 
4. 我们维护一个数组 bestL[r]，初始化为 1，它表示位置 r 处的任意值所强制的最大下界。 对于每个以 r 结尾的出现 k 次的值，我们更新：

 bestL[r] = max(bestL[r], pos[x][i-k+1] + 1)

 这确保了在 pos[x][i-k+1] 或之前开始将恰好包含 k 次出现，但这种方式违反了安全性。 
5. 对于每个 r，所有有效 l 都在 [bestL[r], r] 范围内。 因此以 r 结尾的安全区间数为 r - bestL[r] + 1。 
6. 对所有 r 求和。 

这样做的原因是每个危险配置都由某个值的第 k 个出现窗口唯一标识。 如果一个间隔包含该完整窗口，则它必然会在某个点触发恰好等于 k ​​的频率，这使得该计划变得危险。 通过强制 l 必须大于所有此类左边界，我们将每个无效区间恰好排除一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    pos = {}
    from collections import deque

    dq = {}
    bestL = 1
    ans = 0

    # We maintain for each value a deque of last k positions
    occ = {}

    for r in range(n):
        x = a[r]
        if x not in occ:
            occ[x] = deque()

        occ[x].append(r + 1)

        if len(occ[x]) > k:
            occ[x].popleft()

        if len(occ[x]) == k:
            l_bound = occ[x][0]
            # interval must start after this to avoid exactly k occurrence window
            bestL = max(bestL, l_bound + 1)

        # count valid l for this r
        if bestL <= r + 1:
            ans += (r + 1) - bestL + 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现为每个值保留其最后 k 个出现的滑动双端队列。 这种结构保证了每当我们看到 k 个以 r 结尾的出现时，它们中最左边的一个就定义了以 r 结尾的间隔的最严格约束。 

在此实现中，变量 bestL 在 r 中是全局的，这是一种微妙的简化：在完全严格的公式中，应根据 r 重新计算约束。 然而，由于约束仅随着 r 的增加而向右移动，因此 bestL 是单调的并且安全地累积所有必要的限制。 

必须注意区间数学中基于 1 的索引。 为了在计算计数时清晰起见，该代码将位置转换为从 1 开始。

### 示例 2

 输入：```
6 1
1 2 3 4 5 6
```这里每个值都出现一次。 任何长度至少为 1 的区间都会立即包含频率恰好为 1 的值，因此每个区间都是危险的，除了那些我们完全避免包含任何元素的区间（这对于非空区间来说是不可能的）。 因此答案是0。 

该算法在每一步将 bestL 更新为 r+1，不留下有效间隔，与预期结果匹配。

 ## 边缘情况

 当 k = 1 时，每次发生都会立即形成危险状况。 该算法在每一步将 bestL 设置为 r+1，从而消除所有间隔。 用于输入`1 1 / 1`，在 r = 1 时，occ 大小等于 k，因此 bestL 变为 2，并且没有 l 满足 l ≤ r，从而按预期产生输出 0。 

当所有元素都相同并且 k 很小时，比如说`1 1 1 1 1`当 k = 2 时，每个出现两次的 r 都会迫使 bestL 不断增长。 在 r = 2 时，bestL 变为 1，在 r = 3 时变为 2，依此类推，逐渐缩小有效间隔，直到仅保留那些避免完整 k 块的间隔。 该算法正确地累积约束，因为每个双端队列窗口代表必须避免的不同 k 次出现范围。
