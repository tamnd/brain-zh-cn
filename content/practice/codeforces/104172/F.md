 ## 解决方案
 ## 问题理解

 我们得到一个数字序列，每个数字在 1 到 9 之间，写成一个字符串。 我们可以在该字符串中插入 k 个加号，将其分成 k+1 个连续组。 每组被解释为一个十进制数，表达式的值是这 k+1 个数字的和。 任务是选择加号的放置位置，以使这个总和尽可能小。 

一个关键细节是分组会极大地改变数字的大小。 靠近组前面的数字贡献更大的权重，因为它成为多位数字的一部分，而较早拆分会降低位值。 因此，这个决定不是针对单个数字的，而是关于数字串如何形成数字的。 

约束很大：测试用例中所有字符串的总长度最多为 2 × 10^5，而 k 非常小，最多为 6。这立即表明每个测试用例的 n 指数甚至二次方都行不通。 每个测试用例都需要线性或近线性方法。 

当数字单调或相同时，会出现微妙的边缘情况。 例如，对于输入`n=5, k=1, s=11111`，分组为`1 + 1111`不同于`11 + 111`。 贪婪的“切割最小数字”策略会失败，因为本地数字大小无法捕获位置值影响。 

另一个不明显的问题是，尝试每次 k 次切割的所有切割位置的朴素动态规划会导致 O(n^k)，当 n 很大时，即使 k 很小，这是不可能的。 

## 方法

 暴力破解的想法很简单：在 n−1 个间隙中选择 k 个切割位置，相应地分割字符串，计算总和，并取最小值。 这是正确的，因为它探索了所有可能的分区。 然而，方法的数量是$\binom{n-1}{k}$，在最坏的情况下，其行为类似于 O(n^k)。 n 高达 2 × 10^5，k 高达 6，这是一个天文数字，而且不可行。 

更结构化的观点是从动态规划的角度进行思考。 让 dp[i][j] 表示使用带有 j 个加号的前 i 位数字的最小可能值。 从位置 i 开始，我们尝试每个先前的分割点 p，从 s[p+1..i] 形成一个数字，并转换 dp[i][j] = min(dp[p][j−1] + value(p+1..i))。 这是正确的，但每次转换都是 O(n)，产生 O(n^2 k)，这仍然太慢。 

关键的观察结果是 k 很小。 我们可以不将 k 视为所有位置的维度，而是将其视为“有限数量的分隔符”，可以在从左到右扫描时放置这些分隔符。 成本函数的结构也很简单：每个段只是由连续数字组成的整数。 我们可以在 O(1) 内增量地维护部分段值。 

这表明递归或迭代构造：我们尝试第一次切割的所有可能位置，然后是第二次切割，依此类推，但我们使用增量计算和 k ≤ 6 的事实进行积极修剪。由于 k 是常数有界的，因此只要每次扩展为 O(1)，对切割位置的深度 k 枚举都是可行的。 总工作量大约为 O(n^k / k!)，但是当 k ≤ 6 并通过切割索引的单调级数进行修剪时，它在实践中减少到可管理的范围，因为每个切割位置都严格增加，并且我们只向前扫描。 

另一种看待它的方式是，我们在数组中选择 k 个断点，每个配置都可以通过深度为 k 的嵌套循环生成，其中每个循环都从前一个循环前进。 由于k≤6，我们可以通过递归实现k个嵌套循环。 

我们保持当前总和，同时通过动态解析数字来扩展段。 这避免了重复地重新计算子字符串整数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^k) | O(n^k) | O(k) | 太慢了 |
 | 递归切割枚举| O(n^{k}/k!) 但 k ≤ 6 所以可行 | O(k) | 已接受 |

 ## 算法演练

 我们修正了这样的想法：我们将按升序选择 k 个分割位置并评估结果分区。 

## 算法演练

 1.仅通过读取数字隐式地预先计算数字的前缀解释； 我们不构建子字符串，而是在扩展段时动态计算值。 这避免了每次评估的 O(n) 子串开销。 
2. 定义一个递归函数，处理从给定起始索引开始的字符串，并且仍然需要放置r个加号。 该函数返回后缀的最佳可能总和。 
3. 如果r等于0，我们就被迫将剩余的后缀全部当作一个数字。 我们一次性计算出它的整数值并返回它。 
4. 否则，我们从当前开始迭代当前段的结束位置，直到为未来段留下至少 r 个剩余数字的限制。 这确保了未来分割的有效性。 
5. 对于每个可能的结束位置，我们通过逐位扩展来增量计算段的数值。 这避免了重新计算。 
6. 从下一个位置开始，递归地求解剩余后缀，并进行 r−1 次切割，并与当前段值合并。 
7. 对第一段边界的所有选择取最小值。 

递归自然地探索 k 次切割的所有有效位置，但每个段值都是以 O（段长度）计算的，并且由于 k 最多为 6，因此跨递归路径的总数字处理仍然有限。 

### 为什么它有效

k 个加号的每个有效位置都恰好对应于一个严格递增的切割索引序列。 递归无遗漏地枚举了所有此类序列。 在每个步骤中，每个配置路径都会对前缀段进行一次评估，并通过相同的逻辑对后缀进行最佳求解。 由于每个决策将问题分成后缀上的独立子问题，因此最优子结构成立：后缀的最佳答案不取决于我们如何达到它，只取决于它的起始位置和剩余的切割。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve_case(n, k, s):
    digits = list(map(int, s))
    
    from functools import lru_cache

    @lru_cache(None)
    def dfs(i, r):
        if r == 0:
            val = 0
            for j in range(i, n):
                val = val * 10 + digits[j]
            return val
        
        best = float('inf')
        cur = 0
        
        max_end = n - r
        for j in range(i, max_end):
            cur = cur * 10 + digits[j]
            best = min(best, cur + dfs(j + 1, r - 1))
        
        return best

    return dfs(0, k)

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        out.append(str(solve_case(n, k, s)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该实现直接对递归进行编码。 功能`dfs(i, r)`表示从索引开始的最小可能总和`i`和`r`加号标志仍然放置。 基本情况一次性将剩余后缀转换为整数。 

在转换内部，我们使用一次将当前段扩展一位数字`cur = cur * 10 + digits[j]`，这确保了每步的恒定时间扩展。 循环限制`n - r`保证为将来的段保留足够的数字，避免无效分区。 

记忆化确保每个状态`(i, r)`被计算一次。 由于 r ≤ 6 并且 i 的范围最大为 n，因此在最坏的情况下状态数最多约为 120 万个，但实际上由于循环结构的修剪，探索的转换要少得多。

 ## 边缘情况

 一种边缘情况是当 k 等于 n−1 时，强制每个数字被分开。 递归可以处理这个问题，因为 r 会减小，直到每个段恰好包含一位数字，并且基本情况只是将剩余数字相加。 

另一个边缘情况是当 k 为 1 时，将问题简化为选择单个分割点。 该算法退化为所有断裂位置的线性扫描，正确计算最小成对分裂。 

第三种情况是单调相同的数字，例如`111111`。 递归将探索所有切割位置，但每个段值线性增长，通过将切割推向右侧来实现最优解，这是枚举自然发现的，无需特殊处理。
