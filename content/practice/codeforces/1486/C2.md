 ## 解决方案
 ## 问题理解

 我们得到了一个包含不同值的隐藏数组，我们只能通过查询与它交互。 每个查询都要求一个子段并返回该子段内第二大值的位置（但索引在原始数组中报告）。 

我们的目标是使用最多 20 个此类查询来确定全局最大元素的位置。 

关键的困难在于我们从不直接观察价值观。 每个查询都会返回有关范围内相对顺序的信息，甚至该信息也会发生变化：它给出第二个最大值，而不是最大值。 

约束允许数组大小最大为 100,000，但查询限制是恒定的。 这立即排除了任何单独检查元素或线性缩小搜索范围的策略。 任何正确的解决方案都必须表现得像对数搜索，但适应间接的交互式反馈。 

一个天真的尝试是通过查询单个元素或扫描范围来重复缩小最大值，但这会失败，因为每次查询只显示段的第二个最大值，而这并不能直接告诉我们最大值所在的位置。 

当全局最大值位于端点时，会出现微妙的边缘情况。 例如，如果最大值位于位置 1，则对不包含该最大值的范围的许多查询仍将返回有效的第二个最大值，但它们都不会直接揭示端点结构。 另一种失败情况是，在不跟踪全局上下文的情况下缩小间隔会导致完全失去真正的最大值。 

## 方法

 暴力交互方法会尝试通过测试候选人来推断最大位置。 对于每个位置，我们可以查询包含或排除它的范围，并尝试验证它是否是最大值。 这从根本上来说太慢了：即使验证单个候选者也需要多次查询，并且在最坏的情况下我们需要 O(n) 检查，这在严格的查询限制下是不可能的。 

关键的观察是唯一的全局稳定参考点是整个数组中第二个最大值的位置。 一旦我们查询了整个范围，我们就获得了一个索引 s，它保证是整个数组中的第二大元素。 该元素充当锚点。 

现在考虑将数组分成两半。 唯一的不确定性是哪一半包含最大值。 第二个最大值 s 为我们提供了足够的结构来以对数步数解决这个问题。 在每一步中，我们都会测试一半，并根据答案是否“崩溃”为 s 来决定真正的最大值在哪里。 

这将问题简化为对最大值位置的二分搜索，其中每个步骤对子段使用单个查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力检查候选人 | O(n) 次查询 | O(1) | O(1) | 太慢了|
 | 使用第二最大查询的二分搜索 | O(log n) 次查询 | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们维护一个保证包含最大值的当前搜索段 [l, r]。

1、首先查询全范围[1,n]。 响应给出整个数组中第二大元素的索引 s。 该值在整个过程中保持固定参考。 
2. 现在我们对段 [1, n] 执行二分查找。 在每一步中，计算 mid。 
3. 我们查询当前段 [l, r] 并观察返回的索引 x，它是该段内的第二个最大值。 
4. 如果 s 位于左半部 [l, mid]，则查询右半部 [mid + 1, r]。 如果 s 位于右半部分，我们查询左半部分 [l, mid]。 
5. 关键决策规则是根据返回的第二个最大值是否等于s。 如果查询的一半返回 s，则该一半包含全局最大值和第二个最大值，只有当最大值位于该一半中时才会发生这种情况。 否则，最大值必须位于另一半。 
6. 我们相应地缩小段并继续直到 l == r。 该索引是最大值的位置。 

### 为什么它有效

 正确性取决于全局最大值 p 和全局第二最大值 s 之间的相互作用。 任何同时包含 p 和 s 的段将始终返回 s 作为其第二个最大值。 任何不包含 p 的段都不能返回 s，除非 s 成为该段的最大值，在这种情况下，p 必须位于该段之外。 这种不对称性确保在每一步中，至少可以明确排除一半，从而保留真实最大值始终保留在所选段内的不变量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(l, r):
    print("?", l, r)
    sys.stdout.flush()
    return int(input())

def solve():
    n = int(input().strip())

    # find second maximum position in whole array
    s = ask(1, n)

    l, r = 1, n

    while l < r:
        mid = (l + r) // 2

        if s <= mid:
            # second max is in left half
            res = ask(mid + 1, r)
            if res == s:
                l = mid + 1
            else:
                r = mid
        else:
            # second max is in right half
            res = ask(l, mid)
            if res == s:
                r = mid
            else:
                l = mid + 1

    print("!", l)
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该实现保留单个活动间隔并重复将其减半。 唯一微妙的部分是确保包含 s 的一侧得到不同的处理，因为 s 充当确定查询段是否包含全局最大值的参考。 

所有查询都会立即刷新，因为该解决方案依赖于交互式同步。 

## 工作示例

 考虑一个数组，其中最大值位于左侧，第二个最大值位于右侧。 

| 步骤| 查询 | 回应 | 区间决策|
 | --- | --- | --- | --- |
 | 1 | [1, 5] | s = 3 | 全系列已知|
 | 2 | mid = 3, 查询 [4, 5] | 4 ≠ s | 左半部分最大|
 | 3 | 新区间 [1, 3] | 继续 | 向左收缩|
 | 4 | 决赛| 1 | 找到答案 |

 此跟踪显示了与 s 的不匹配如何立即消除不能包含最大值的一半。 

现在考虑相反的配置，其中最大值和第二最大值位于同一半。 

| 步骤| 查询 | 回应 | 区间决策|
 | --- | --- | --- | --- |
 | 1 | [1, 5] | s = 3 | 参考固定|
 | 2 | mid = 3, 查询 [4, 5] | s | 右半部分包含两个顶部元素 |
 | 3 | 向右移动| [4, 5] | 正确收缩|
 | 4 | 决赛| 4 | 最大发现|

 这证实了当 half 包含两个顶部元素时，它会被保留。

 ## 边缘情况

 当最大值位于数组边界时，第二个最大值仍然存在于相反的一侧，因此第一次全范围查询立即修复了一个正确的引用 s，并且二分查找干净地隔离了包含最大值的一侧。 

当第二个最大值非常接近最大值时，两者可能在早期分裂期间落入同一半。 在这种情况下，查询的一半返回 s，迫使算法保留该一半直到最后一步，其中间隔正确折叠到最大索引。 

在所有情况下，当前间隔始终包含真实最大值的不变式确保不会发生错误消除，因为只有当证明第二最大值查询的行为无法包含最大值时，才会删除一半。
