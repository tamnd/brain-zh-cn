 ## 解决方案
 ## 问题理解

 问题询问一个包是否恰好包含`x`巧克力块可以使用 Felix 的超立方体包系列来平衡。 可用的封装有尺寸`1, w, w², ..., w¹⁰⁰`， 在哪里`w`是每个超立方体的边长。 菲利克斯可以将任何包裹放在天平的任一侧，因此每个包裹的力量`w`可以对最终差异产生积极、消极或根本没有影响。 任务是回答是否`x`可以表示为这些幂的总和，系数为`{-1, 0, 1}`。 

输入最多包含 20 个待检查的包裹重量，每个重量最多为`10^9`。 基地`w`介于 2 到 10 之间。由于我们需要的最大可能指数很小，因为`10^10`已经超过`10^9`，一个在基数中逐位工作的解决方案`w`很容易足够快。 对 101 个可能的立方体的选择进行强力搜索将有多达`3^101`状态，这是完全不可能的，因此解决方案必须利用幂的数学结构。 

错误的主要来源是假设正常基础`w`代表性就足够了。 事实并非如此，因为普通数字可以大于 1，而每个数字的幂`w`只能使用一次。 进位可以将数字移动到下一个位置并使其有效。 

例如：```
Input:
4 5
25
```输出是：```
YES
```价值`25`不表示为仅使用正常基数 5 数字的总和`0`和`1`因为它是`100_5`，但它可以通过取`5²`立方体，所以答案是肯定的。 

另一个棘手的情况是当数字无法直接表示并且需要进位时：```
Input:
4 5
29
```输出是：```
YES
```因为`29 = 25 + 5 - 1`。 只检查每个以 5 为基数的数字是否最多为 1 的贪婪实现会错误地拒绝这一点。 

## 方法

 最简单的方法是尝试每个超立方体的所有可能选择。 的每一个功率`w`有三种状态：放在菲利克斯这边，放在他妈妈那边，或者忽略它。 这种方法是正确的，因为它列举了天平秤上所有可能的排列。 然而，可能性的数量随着`3^101`，这远远超出了可以处理的范围。 

有用的观察是，`w`行为与基地中的位置完全相同`w`号码系统。 余额限制意味着每个仓位都需要一位数字`-1`,`0`， 或者`1`。 我们可以重复检查最低的基数，而不是决定使用哪些立方体`w`的数字`x`。 如果该数字是`0`或者`1`，我们可以直接使用它。 如果它更大，我们可以通过在该位置使用负立方体减去该数字的一个副本，并将其移至下一个位置。 这与将数字转换为带符号的数字表示形式相同。 

例如，在基数 5 中，数字 29 有数字`104_5`。 最后一位数字是 4，这是不允许的。 我们将其替换为`-1`并将一个带到下一个位置：```
104_5
= 110_5 - 1
= 1 * 5² + 1 * 5 - 1
```蛮力法之所以有效，是因为它考虑了所有放置位置，但由于放置位置太多而失败。 观察到每个决策都可以通过基数转换在本地处理，从而将问题简化为短数字处理循环。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(3^101) | O(3^101) | 奥(101) | 太慢了|
 | 有符号基数转换| 每个查询 O(log_w(x)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将当前值转换为基数`w`重复取一次一位数字`x % w`。 
2. 如果当前数字是`0`或者`1`，通过执行整数除以将其从数字中删除`w`。 这些数字已经与允许的系数匹配。 
3. 如果当前数字大于`1`，在这个位置放置一个负立方体。 从数学上讲，这意味着替换数字`d`和`d - w`并将进位 1 添加到下一个位置。 自从`w`最多 10，其中每个可能的数字`2`到`9`可以这样修正。 
4. 继续直至剩余值变为零。 如果处理了每个数字，则该数字具有有效的签名表示形式。 

转换始终有效的原因是每个整数都有唯一的余数模`w`。 当余数大于1时，使用`-1`在这个位置留下多个`w`，可以进位到下一个数字。 该过程不断减少剩余数字的大小，因此最终完成。 

为什么它有效：

 在每一步，算法都保持相同的不变量：所选立方体已经表示的数量加上剩余值仍然等于原始目标`x`。 选择一个数字`0`或者`1`消耗确切的数量。 选择`-1`消耗`-1`当前功率并移动多余的`w`通过进位将单位转移到下一个位置。 当没有剩余值时，仅使用系数来表示整个数字`-1`,`0`， 和`1`，它完全对应于有效的平衡安排。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def possible(x, w):
    while x:
        digit = x % w
        if digit <= 1:
            x //= w
        else:
            x = (x // w) + 1
    return True

def solve():
    n, w = map(int, input().split())
    ans = []
    for _ in range(n):
        x = int(input())
        ans.append("YES" if possible(x, w) else "NO")
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```这`possible`函数执行有符号基数转换。 余数运算提取当前基数`w`数字。 当数字为`0`或者`1`，正常除法会删除该数字。 当数字较大时，表达式`(x // w) + 1`执行进位到下一个位置。 

无需显式跟踪负数，因为唯一的问题是是否存在有效的选择。 每个大于 1 的数字总是可以被带有进位的负数替换。 循环条件还避免了任何固定指数限制，因为在给定约束下仅经过少量迭代后该值就变为零。

对于价值`32`：

 | 步骤| 当前值| 数字（`value % 5`) | 行动| 新价值|

 | 1 | 32 | 32 2 | 使用`-1`并携带| 7 |

 该跟踪仍然成功完成，表明允许重复进位。 然而，这不是正确的样本结果，因为最初的解释要求每个单独的超立方体大小仅存在一次`w^100`。 自从`32`以 5 为基数需要归一化后系数大小大于 1，因此无法构建。 因此，上面的实现必须直接检查带符号的数字。 

正确的实现需要检测这种情况：```
def possible(x, w):
    while x:
        digit = x % w
        if digit == 0 or digit == 1:
            x //= w
        elif digit == w - 1:
            x = x // w + 1
        else:
            return False
    return True
```使用这个版本，`32`失败，因为基数 5 的余数为`2`，不能用任何一个来表示`1`或者`-1`。 

对于样本值`25`：

 | 步骤| 当前值| 数字（`value % 5`) | 行动| 新价值|
 | ---| ---| ---| ---| ---|
 | 1 | 25 | 25 0 | 删除数字 | 5 |
 | 2 | 5 | 0 | 删除数字 | 1 |
 | 3 | 1 | 1 | 使用正立方体 | 0 |

 零位对应空位，最后一位使用`5²`立方体。

 ## 边缘情况

 一个值恰好是`w`是最简单的情况。 例如：```
Input:
1 5
25
```数字是`100_5`。 该算法删除零位数字并接受最后一位数字，与方形超立方体的使用相匹配。 

数字为的值`w - 1`需要携带。 例如：```
Input:
1 5
26
```号码是`101_5`。 它可以表示为`25 + 1`，所以算法只看到数字`1`,`0`， 和`1`并接受它。 

包含两者都不是的数字的值`0`,`1`，也不`w - 1`一定会失败。 例如：```
Input:
1 5
27
```以 5 为基数的表示形式包含一个数字`2`。 这将需要使用同一个立方体的两个副本或等效的无效系数，因此算法会立即拒绝它。 

这些案例涵盖了问题的主要故障模式：将普通基本表示与天平秤所需的受限有符号表示混淆。
