 ## 解决方案
 # 问题理解

 弗朗辛收集了一些单独的数字，并希望将其中一些数字排列成巴斯特认为令人毛骨悚然的最大可能数字。 幽灵数字是一个能被 2、3 和 5 整除的非负整数，这与能被 30 整除是一样的。她可能会丢弃一些数字，因为亚瑟添加了不需要的数字，但剩余的数字必须形成最大可能的值，并且不能包含不必要的前导零。 

输入给出可用数字的数量，然后给出数字本身。 输出是这些数字可以被 30 整除的最大整数。如果不存在这样的数字，我们打印`-1`。 

该限制允许最多 100000 个数字。 任何尝试不同安排或检查许多可能子集的方法都是不可能的，因为候选者的数量呈指数增长。 即使尝试大部分数字的所有排列也会立即超出可用时间。 该解决方案需要处理数字恒定次数，这指向 O(n) 或 O(n log n) 方法。 

在某些情况下，粗心的实施可能会失败。 单个零是有效答案，因为零可以被每个非零除数整除。 例如，输入```
1
0
```必须产生```
0
```需要非零前导数字的解决方案会错误地拒绝它。 

另一个陷阱是忘记了被 30 整除需要末尾有一个零。 例如，```
4
3 3 6 6
```数字和为 18，可被 3 整除，并且包含偶数位，但没有零。 正确的输出是```
-1
```因为没有任何排列可以被 5 整除。 

最后一个常见错误是在固定数字和时删除了错误的数字。 考虑```
5
1 1 1 2 0
```总和是 5，因此必须删除一位数字才能使总和能被 3 整除。`2`给出最大的答案：```
1110
```删除一个`1`给出`2100`，较小。 移除过程必须保留最大可能的剩余数量。 

## 方法

 暴力破解的想法是生成可用数字的可能子集，按降序排列每个选定的子集，并检查结果数字是否能被 30 整除。这是正确的，因为所有可能的有效答案都出现在这些候选值中，然后可以选择最大的一个。 

问题是最多有100000位数字。 子集的数量为 2^n，甚至存储或检查其中的一小部分也是不可能的。 蛮力方法失败了，因为它将数字视为独立的选择，而不是使用准确描述重要内容的整除规则。 

关键的观察结果是，能被 30 整除的结构非常简单。 能被 30 整除的数字必须能被 10 整除，因此它的末尾必须包含一个零。 它还必须能被 3 整除，这仅取决于其数字之和。 其他数字的确切顺序不影响被 3 整除。 

问题变成选择要删除的数字。 由于我们想要尽可能大的数字，因此我们应该保留尽可能多的数字。 如果数字和已经能被3整除，我们只需要把所有可用的数字按降序排列即可。 否则，我们删除使总和能被 3 整除的尽可能少的数字。之后，对剩余数字进行排序即可得到最大排列。 

唯一对删除重要的数字是其模 3 的余数。为了将总和减 1 模 3，我们删除余数为 1 的最小数字。为了减少模 3 的 2，我们删除余数为 2 的最小数字。如果单个数字不可用，则删除相反余数的两位数字可以达到相同的效果。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算所有数字并计算它们的总和。 总和告诉我们当前模 3 的余数，这是被 3 整除所需的唯一信息。 
2. 检查是否至少有一个零。 如果没有零，这个数字就不能被10整除，所以就不存在幽灵般的数字。 
3. 如果数字和不能被 3 整除，则删除固定余数的最小可能数字或数字对。 移除的值越小，最终的数字越大。 
4. 将剩余数字按降序排列。 数字相同的数，当最高位先出现时，该数最大。 
5. 打印结果数字。 如果唯一剩余的表示为零，则打印单个零而不是多个前导零。 

工作原理：该算法仅在 3 的整除性规则需要时才删除数字。删除较少的数字总是保留数字较多的数字，该数字比同一集合中数字较少的任何数字都大。 当需要移除时，选择尽可能小的可移除数字留下最大的剩余数字多组。 最后，降序排序会产生该多重集中的最大数字。 零的存在保证能被 10 整除，而校正后的数字和保证能被 3 整除，因此结果总是能被 30 整除。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    digits = list(map(int, input().split()))

    if 0 not in digits:
        print(-1)
        return

    total = sum(digits)
    rem = total % 3

    if rem != 0:
        removed = False

        for i, d in enumerate(digits):
            if d % 3 == rem:
                digits.pop(i)
                removed = True
                break

        if not removed:
            need = (3 - rem) % 3
            to_remove = []
            for i, d in enumerate(digits):
                if d % 3 == need:
                    to_remove.append(i)
                    if len(to_remove) == 2:
                        break

            if len(to_remove) < 2:
                print(-1)
                return

            for i in reversed(to_remove):
                digits.pop(i)

    digits.sort(reverse=True)

    if digits[0] == 0:
        print(0)
    else:
        print("".join(map(str, digits)))

if __name__ == "__main__":
    solve()
```该解决方案首先拒绝不带零的情况，因为无论进行多少重新排列都无法创建以零结尾的数字。 这避免了不必要的工作并直接处理被 10 整除的要求。 

数字和用于决定是否需要进行任何删除。 删除一位数字时，代码会搜索具有所需余数的最小数字，因为删除的数字越小，答案越大。 如果一位数字不够，则删除两位数字，具有相同的组合余数效果。 

最后的降序排序是将所选数字转换为最大可能的整数。 专项检查针对的是`digits[0] == 0`处理每个剩余数字都为零的情况，防止诸如`0000`。 

Python 整数在这里不会溢出，因为该算法从不以数字方式构造数字。 它将答案构建为一串数字，这是必要的，因为答案可以包含 100000 个数字。

 ## 边缘情况

 对于仅零的情况：```
1
0
```该算法找到零，计算零的数字和余数，跳过删除，对列表进行排序，并发现第一个数字为零。 它输出一零。 这可以防止将零视为无效数字的常见错误，因为它没有非零前导数字。 

对于缺失零的情况：```
4
3 3 6 6
```该算法立即无法满足能被 10 整除的要求，因为不存在零。 它输出`-1`在尝试删除任何数字之前。 删除数字无济于事，因为每个有效的令人毛骨悚然的数字都必须以零结尾。 

对于数字和需要修正的情况：```
5
1 1 1 2 0
```总和为 5，余数为 2 模 3。该算法搜索余数为 2 的数字并删除该数字`2`。 其余数字的和为 3，包含零，排序为`1110`。 删除任何`1`相反会留下一个较小的数字。 

对于多个零：```
3
0 0 0
```所有可能的排列都代表零。 排序后，算法检测到第一个数字为零并仅打印一个数字。 这可以处理表示问题，同时保留数学值。
