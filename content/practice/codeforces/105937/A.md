 ## 解决方案
 ## 问题理解

 我们进行了一轮非常简单的纸牌游戏，其中恰好抽出了三张牌。 每张卡都有一个 1 到 13 之间的整数值。该轮的分数通常只是三个值的总和。 不过，有一个特殊的规则：如果所有三张牌都显示相同的值，则该玩家具有“三重匹配”条件，并且最终得分额外增加100分。 

因此，任务纯粹是计算三个整数的修改后的总和，并根据所有三个输入是否相同提供条件奖励。 

限制很小，因为我们在一个测试用例中只读取了三个数字。 这立即排除了对数据结构或优化问题的任何需求。 即使在计算总和后进行简单的条件检查也足够了。 

不存在涉及排序或多个测试用例的隐藏边缘情况。 唯一有意义的角落是当所有值都相等时，包括最小可能的情况，如 1 1 1 或最大的情况，如 13 13 13。另一个简单的边界是当两个值匹配但第三个值不同时，例如 5 5 6，即使存在部分重复，也不应应用奖励。 

这里的一个天真的错误是，只要任何两张牌匹配，就会错误地应用奖金，而不是要求所有三张牌完全匹配。 

## 方法

 暴力破解的观点是从字面上解释规则：计算所有三张牌的总和，然后检查这三个值是否相等。 如果是，请添加奖金。 

这里没有真正的组合爆炸或搜索空间，因为输入大小是恒定的。 即使我们想象将其推广到更多卡，该结构仍然是对集合的单遍相等性检查。 

关键的观察结果是评分规则分为两个独立的部分：加性成分（总和）和条件指标（全部相等）。 总和始终与牌的数量呈线性关系，相等条件简化为检查 a1 是否等于 a2 且 a2 是否等于 a3。 

因此，解决方案只需进行一次算术和比较，从而使其有效 O(1)。

 ## 算法演练

 1. 从输入中读取三个整数 a1、a2 和 a3。 这些代表抽到的牌的值。 
2. 通过将它们相加来计算基本分数：s = a1 + a2 + a3。 这反映了没有任何奖金的正常评分规则。 
3. 通过验证 a1 == a2 和 a2 == a3 来检查所有三个值是否相同。 这个两个比较链就足够了，因为相等是传递的。 
4. 如果条件成立，则将分数增加 100。否则，保持不变。 
5. 输出最终得分。 

### 为什么它有效

 评分函数被定义为线性和加上二元指示函数，该函数仅取决于所有三个输入是否相等。 相等性检查准确地捕获了“炸弹”配置的定义，并且总和与顺序或重复结构无关。 由于卡片之间没有其他交互，因此将这两种计算结合起来可以产生准确的所需分数，而不会遗漏或重复计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

a1, a2, a3 = map(int, input().split())

score = a1 + a2 + a3

if a1 == a2 == a3:
    score += 100

print(score)
```该解决方案在一行中读取三个整数并直接计算它们的总和。 链式比较`a1 == a2 == a3`是验证所有三个值是否相同的最简洁、最正确的方法。 

只有在“全部相等”的情况下才会触发条件加100，这符合炸弹的定义。 由于没有额外的规则或交互，因此不需要进一步的逻辑。

## 测试用例```python
import sys, io

def solve():
    a1, a2, a3 = map(int, input().split())
    score = a1 + a2 + a3
    if a1 == a2 == a3:
        score += 100
    print(score)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as sio
    out = sio.StringIO()
    with redirect_stdout(out):
        solve()
    sys.stdin = old_stdin
    return out.getvalue().strip()

# provided samples
assert run("6 6 6") == "118"
assert run("1 1 4") == "6"

# custom cases
assert run("1 2 3") == "6"
assert run("13 13 13") == "139"
assert run("5 5 6") == "16"
assert run("1 2 2") == "5"
```| 测试输入| 预期产出 | 它验证了什么 |

 | 13 13 13 | 13 13 13 139 | 139 奖金最大值 |
 | 5 5 6 | 5 5 6 16 | 16 部分匹配不触发奖励 |
 | 1 2 2 | 1 2 2 5 | 混合订购，仍然没有奖金 |

 ## 边缘情况

 唯一有意义的边缘情况是区分完全平等和部分平等。 用于输入`5 5 6`，算法计算总和 16 并正确地跳过奖金，因为`a1 == a2`是真的但是`a2 == a3`是假的，所以链式相等失败。 

为了`1 1 1`，条件`a1 == a2 == a3`计算结果为 true，因此算法将 100 加到基数 3 上，生成 103。这直接符合“炸弹”规则。 

为了`13 13 13`，相同的逻辑适用于上限，产生 39 + 100 = 139。比较逻辑不受值大小的影响，从而确认整个输​​入范围内的正确性。
