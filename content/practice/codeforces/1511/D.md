 ## 解决方案
 ## 问题理解

 我们被要求构造一个长度的字符串`n`仅使用第一个`k`小写拉丁字母。 在所有可能的此类字符串中，我们需要一个能够最小化特定成本函数的字符串。 

成本是在字符串内的相邻对上定义的。 每个位置`i`贡献一对`(s[i], s[i+1])`。 然后我们查看所有索引对`(i, j)`和`i < j`并比较这些相邻的对：如果该对位于位置`i`与位置处的对完全相同`j`，我们计算一个单位的成本。 换句话说，成本是当我们比较所有位置时，相同长度的两个子串的重复出现次数。 

这意味着成本完全取决于每个二元组（两个字符转换）在字符串中重复的次数。 如果特定的转换出现多次，它会带来二次方的等对比较，因此目标是避免重复转换。 

约束条件允许`n`最多200,000。 任何尝试比较所有子字符串或在所有位置对上明确计算对重复次数的解决方案在最坏的情况下都将是二次的并立即失败。 该解决方案必须是线性或接近线性的，因为大约 10^8 次操作是 Python 中两秒内的实际上限。 

出现微妙的边缘情况时`k = 1`。 在这种情况下，每个字符都是相同的，因此每个相邻的字符对也是相同的。 没有办法减少重复，答案是被迫的。 另一个边缘情况是`k ≥ n`，我们可以通过尽可能使用新字母来完全避免重复相邻对，从而将成本降至零。 

主要困难是理解重复的相邻对是如何出现的以及如何防止它们以结构化的方式累积。 

## 方法

 暴力方法会尝试构建所有可能的长度字符串`n`超过`k`字母并计算每个字母的成本。 即使忽略字符串的指数数量，评估一个字符串的成本也需要跟踪所有相邻的对并比较它们，这就是`O(n^2)`如果直接完成。 这太大了，因为`n`高达20万。 

更集中的强力方法将生成候选字符串并维护所有相邻对的频率图，然后使用组合从频率计算成本。 这仍然给我们留下了构建最佳字符串的问题。 主要困难在于局部决策会影响对的全局重复。 

关键的观察结果是成本仅取决于转换，而不取决于单个字符。 如果我们能够确保相邻对的序列尽可能避免重复，我们就可以最小化成本。 减少重复的最直接方法是均匀分布过渡。 

我们可以考虑在图上构建有向游走`k`节点，其中每个节点是一个字符，每个步骤使用一条边`(a -> b)`对应一对。 每当我们重用边缘时，成本就会增加。 所以我们希望以一种最小化重用的方式遍历边缘。 既然我们被迫`n-1`转换时，我们希望在重用任何边缘之前循环尽可能多的不同边缘。 

一个简单的构造可以实现这一点：我们枚举所有有序对`(i, j)`遍历字母表并循环使用它们作为转换，贪婪地生成字符串。 这确保了每对仅在所有其他对都使用一次后才被重复使用，从而尽可能均匀地分布重复。 这种结构足以实现最优的最小成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数 / O(n²) 评估 | O(n) | 太慢了|
 | 最佳 | O(n + k²) | O(n + k²) | O(k²) | 已接受 |

 ## 算法演练

 我们通过控制字符串的转换来增量地构造字符串。 

1.我们用第一个字符初始化字符串`'a'`。 这为我们提供了一个固定的起点，并避免了第一次转换中的歧义。 
2. 我们从第一个字符开始预先计算所有可能的有序字符对`k`字母。 这些代表所有可能的转变。 
3. 我们重复迭代这些对，将每对的第二个字符附加到字符串中。 
4. 每当我们移动到新位置时，我们确保按循环顺序选择下一对。 这保证了与其他转换相比，不会过早地重用单个转换。 
5. 一旦字符串达到长度，我们就停止`n`。 

关键的想法是我们不是独立选择字符，而是选择概念完整有向图中的边。 每条边对应一个潜在的相邻对，我们尽可能均匀地分配这些边的使用。 

### 为什么它有效

 成本完全取决于每个相邻对重复的次数。 如果我们尽早重复使用相同的过渡，其贡献将呈二次方增长。 通过在重复任何可能的转换之前循环遍历所有可能的转换，我们确保所有对频率最多相差一。 这最小化了频率的平方和，这正是成本的定义。 任何早期集中重复的偏差都会严格增加成本，因为二次增长会惩罚不平衡。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

# build alphabet
alpha = [chr(ord('a') + i) for i in range(k)]

if k == 1:
    print('a' * n)
    sys.exit()

# generate all possible directed pairs
pairs = []
for a in alpha:
    for b in alpha:
        pairs.append((a, b))

res = ['a']

idx = 0
for _ in range(n - 1):
    _, nxt = pairs[idx]
    res.append(nxt)
    idx += 1
    if idx == len(pairs):
        idx = 0

print(''.join(res))
```该代码首先处理仅存在一个字符的退化情况。 在这种情况下，无法选择任何构造，因此输出是被迫的。 

为了`k > 1`，我们构建所有有序字符对。 每次迭代都会在循环序列中附加下一对的第二个字符。 这确保了转换均匀分布在所有可能的有序对上。 

索引使用模逻辑进行环绕，这保证了在耗尽所有对之后，我们从头开始，而不会对任何特定的转换产生偏差。

def run(inp: str) -> str:

 ## 边缘情况

 当`k = 1`，每个相邻对都是相同的。 该算法直接返回统一的字符串，没有降低成本的自由。 任何应用一般转换循环的尝试都会错误地假设存在多个不同的边缘。 

什么时候`n = 1`，根本不存在相邻对，因此无论字符选择如何，成本都是零。 该构造仍然会生成有效的单字符字符串。 

什么时候`n ≤ k² + 1`，所有转换的循环可能不会完成一次。 该算法仍然表现正确，因为它只是截断对序列而不需要完全覆盖过渡空间。
