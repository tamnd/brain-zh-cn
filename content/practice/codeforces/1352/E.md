 ## 解决方案

 ## 问题理解

 给定一个正整数数组，我们想要确定哪些元素可以“解释”为长度至少为 2 的数组的连续段的和。 对于数组中出现的每个值，我们检查数组中的某个位置是否存在长度为 2 或以上的子数组，其总和等于该值。 即使多个索引包含相同的数字，也会对值满足此条件的每个索引进行计数。 

关键的困难在于该定义在数组上是全局的：位置 i 处的值不需要由涉及 i 本身的子数组形成。 数组中任何位置的任何段都是有效的，只要其总和等于该值。 

限制严格在于结构而不是规模。 每个测试用例总共最多有 8000 个元素，每个元素最多为 n。 朴素的三次解会迭代每个位置的所有子数组，导致大约 O(n3) 的行为，这远远超出了可接受的范围。 即使每个测试用例的 O(n²) 解决方案也处于边缘状态，但如果仔细实施，则可以接受，因为所有测试的总 n 是有界的。 

一个微妙的点是许多值重复。 这很重要，因为我们不需要独立地重新计算某个值对于每个事件是否都是特殊的。 相反，我们可以预先计算哪些值可以表示为子数组和，然后计算频率。 

当试图只考虑以每个索引开始或结束的子数组时，就会出现一种常见的失败情况。 例如，在像这样的数组中`[1,2,3,4]`，值`3`很特别，因为`1+2=3`，但是如果仅检查包含该索引的段，则围绕每个索引的边界限制扫描可能会错过它。 

## 方法

 蛮力的想法很简单。 我们枚举长度至少为 2 的每个子数组，计算其总和，并将该总和标记为可实现。 之后，我们扫描数组并计算这个“可实现的总和”集中出现的元素数量。 

这是正确的，因为它直接遵循定义。 问题是枚举所有子数组的成本。 有 O(n²) 个子数组，计算每个总和时会添加 O(n) 的另一个因子，得到 O(n³)。 即使前缀和将每个子数组的总和减少到 O(1)，我们仍然有 O(n²) 个子数组，这对于 n 总计为 8000 的情况是可以接受的，但需要仔细修剪。 

关键的观察是我们实际上并不需要所有子数组。 由于所有值都以 n 为界，因此可以立即忽略总和大于 n 的任何子数组。 这大大减少了起始索引的有用扩展的数量，因为一旦运行总和超过 n，进一步的扩展只会增加它。 

这将问题转换为有界两指针或从每个起始位置扩展窗口扫描，每当总和变得太大时我们就会提前停止。 由于每个内循环最多在总和超过 n 时停止，因此在最坏情况下迭代总数大约为 O(n²)，但实际上要低得多，并且在约束下可以接受。 

我们将所有可实现的总和存储在一个布尔数组中，最多为 n，然后计算原始数组中标记为可达的值的频率。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（所有子数组）| 具有前缀和的 O(n3) 或 O(n2) | O(n) | 太慢了|
 | 有界两指针扩展 | 最坏情况为 O(n²)，实践中更快 | O(n) | 已接受 |

 ## 算法演练

 1. 预先计算输入值的频率数组。 这让我们可以在预处理可达总和后以 O(n) 的方式计算结果。 
2. 创建布尔数组`good[v]`表示是否值`v`可以形成为长度至少为 2 的子数组的和。由于值最多为 n，因此我们最多只能跟踪 n。 
3. 对于每个起始索引`i`，将运行总和初始化为 0。我们将子数组向右扩展。 
4. 对于每个`j >= i`， 添加`a[j]`到运行总和。 如果`j > i`（保证长度至少为2），且总和≤n，标记`good[sum] = True`。 
5. 如果运行总和超过n，则立即跳出循环，因为所有进一步的扩展都只会增加总和而不会变得有效。 
6. 处理完所有起点后，通过求和计算答案`freq[v]`为所有人`v`这样`good[v]`是真的。 

当总和超过 n 时，关键的修剪步骤是中断。 由于所有数组元素均为正数，因此当我们扩展子数组时，总和会严格增加，因此以后的扩展无法将总和带回到有效范围内。 

### 为什么它有效

 正确性取决于两个属性。 首先，每个长度至少为 2 的子数组都被视为一对索引 (i, j) 一次。 其次，因为所有数字都是正数，所以固定起始索引的运行总和随着 j 的增加而单调增加。 这保证了一旦总和超过n，进一步的扩展就不能产生有效的目标，因此剪枝是安全的。 在该截止点之前仍会访问每个可实现的总和，因此不会错过任何有效值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        freq = [0] * (n + 1)
        for x in a:
            if x <= n:
                freq[x] += 1
        
        good = [False] * (n + 1)
        
        for i in range(n):
            s = 0
            for j in range(i, n):
                s += a[j]
                if s > n:
                    break
                if j > i:
                    good[s] = True
        
        ans = 0
        for v in range(1, n + 1):
            if good[v]:
                ans += freq[v]
        
        print(ans)

if __name__ == "__main__":
    solve()
```频率数组将计数与可达性计算隔离开来。 这种分离避免了重复扫描数组中的每个和。 

嵌套循环枚举所有子数组，但当总和超过 n 时提前终止。 条件`j > i`强制只有长度至少为 2 的子数组才起作用。 

最后，我们通过将原始值与预先计算的可达集进行匹配来聚合结果。

 ## 边缘情况

 例如，当所有元素都很大时，就会出现棘手的情况`[8,7,6,5]`。 尽管存在许多子数组，但几乎所有总和都很快超过 n，因此只有非常短的段才重要。 该算法正确地提前中断并避免不必要的探索，确保正确性而不需要额外的成本。 

另一种情况是当数组包含多个时。 尽管子数组很多，但和增长缓慢，并且产生许多小和。 该算法仍然正确枚举它们并标记所有可达值，而不会丢失重复项或过度计数。 

最后一个微妙的情况是单元素数组。 由于不存在长度至少为 2 的子数组，因此答案始终为零。 条件`j > i`确保不会发生错误标记。
