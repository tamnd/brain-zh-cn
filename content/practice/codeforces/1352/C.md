 ## 解决方案

 ## 问题理解

 我们正在研究一个经过过滤的正整数序列，其中固定数字的每个倍数都被删除。 想象一下标记所有可被整除的数字，而不是使用自然数的完整列表`n`作为禁止的，然后将剩余的内容压缩成一个干净的序列。 任务是确定哪个数字出现在位置上`k`这个压缩序列。 

关键的困难在于过滤后的序列没有明确给出。 对于较大的值，序列会非常长，因此我们需要一种方法可以直接跳转到答案，而无需逐个枚举元素。 

这些限制使得简单的模拟变得不可行。 既然两者`n`和`k`最多可以有 10 亿个，并且最多可以有 1000 个测试用例，在最坏的情况下，任何迭代整数并检查整除性的方法都需要每个测试用例最多 10^9 次操作。 这远远超出了一秒钟的运行速度。 

出现微妙的边缘情况时`n`很小。 例如，如果`n = 2`和`k = 1`，答案是`1`，但如果错误地计算索引并从零开始或包含多个`n`，相差一位的转变会迅速传播。 另一个边缘情况是当`n`非常大，比如`n = 10^9`。 在这种情况下，除了每十亿步中有一个数字之外，几乎每个数字都是有效的，因此答案非常接近`k`，而简单的过滤会浪费几乎所有不应删除的数字上的工作。 

## 方法

 蛮力方法会迭代正整数，维护一个计数器，记录有多少数字不能被整除`n`，并在到达时停止`k`- 第一个有效数字。 这是直接且正确的，因为它直接模拟了序列的定义。 然而，其成本取决于我们扫描的数字数量。 在最坏的情况下，如果`n = 2`，只有一半的数字是有效的，所以我们可能需要粗略地检查一下`2k`每个测试用例的数量。 和`k`直到10^9，这变得完全不可能。 

关键的观察是停止逐步思考序列，而是分块推理。 在每一个街区`n`精确地连续整数`n - 1`它们中的一个是有效的，因为每个块中只有一个数字可以被`n`。 这将问题转化为对完整块进行计数，然后处理部分块内的余数。 

一旦识别出这个结构，我们就可以计算有多少个完整的块大小`n`需要达到`k`-th 有效数字，然后调整跳过的缺失倍数。

 | --- | --- | --- | --- |
 | 蛮力 | 每次测试 O(k) | O(1) | O(1) | 太慢了|
 | 最佳| 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算有多少个完整的组`n`需要数字来覆盖`k`有效数字。 各组贡献`n - 1`有效数字，所以我们除以`k`经过`n - 1`。 这告诉我们在到达目标位置之前可以容纳多少个完整的块。 
2. 计算这些完整块之后所需的剩余有效数字。 这个余数决定了答案在下一个块中的距离。 
3. 通过将完整块的数量乘以，将块计数转换为实际的数字位置`n`。 这给出了原始整数行中的基线位置，该位置说明了跳过的倍数。 
4. 如果余数不为零，则我们向前移动该余数以得到正确的有效数字。 如果余数为零，则我们正好位于边界处，必须后退 1 以避免落在 的倍数上`n`。 

### 为什么它有效

 核心不变量是每个连续的段`n`整数恰好包含`n - 1`有效数字，以及固定偏移处恰好一个被排除的数字（`n`）。 通过将数轴分组为大小相等的块，我们将分散的去除过程转变为周期性模式。 这种周期性保证了全局计算有效数相当于计算整个块加上单个块内的局部调整，因此在将序列压缩为块算术时不会丢失任何信息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())

        # number of full blocks of size (n-1) valid numbers
        blocks = (k - 1) // (n - 1)

        # position after accounting for removed multiples
        ans = blocks * n + (k - blocks * (n - 1))

        print(ans)

if __name__ == "__main__":
    solve()
```该实现直接对块推理进行编码。 表达式`(k - 1) // (n - 1)`计算有多少个完整的`(n - 1)`- 大小的有效数字组在到达之前适合`k`。 乘以`n`将这些组移回原始数轴，重新插入跳过的倍数。 

最终调整添加当前块内的剩余偏移量。 块计算中减 1 对于避免差一错误至关重要`k`正好可以整除`n - 1`，答案应该落在多个的之前`n`，不在上面。 

## 工作示例

 我们追踪两个案例来看看块结构如何取代显式枚举。 

第一个例子：`n = 3, k = 7`。

 | --- | --- | --- | --- |
 | 计算块| 3 | (7-1)//2 = 3 | 3 整块 |
 | 基本位置| 3 | 3 * 3 = 9 | 3 * 3 = 9 起点|
 | 余数 | 1 | 7 - 6 = 1 | 7 - 6 = 1 移动 1 步 |

 这表明，在考虑了三个大小为 3 的完整块（每个块贡献 2 个有效数字）后，我们落在 9 附近，然后在下一个块内进行调整。 

第二个例子：`n = 4, k = 12`。 

| 步骤| 块| 余数逻辑 | 结果 |

 | 基本位置| 3 | 3 * 4 = 12 | 3 * 4 = 12 | 起点|
 | 余数 | 3 | 12 - 9 = 3 | 12 - 9 = 3 | 移动 3 步 |
 | 最终答案| - | - | 15 | 15

 这证实了完整的块贡献结构，而其余部分处理块内的局部定位。

 ## 边缘情况

 当`k`非常小，比如`k = 1`，该公式仍然有效，因为`(k - 1) // (n - 1)`变为零，将答案正确地放在第一个有效数字处，该数字始终是`1`。 

什么时候`k`恰好是`n - 1`，计算精确地落在块的边界处。 在这种情况下，乘以`n`确保我们正确地跳过排除的倍数，并且余数调整避免踏入禁止的倍数。 

什么时候`n`非常大，块大小变得非常稀疏，几乎每个数字都是有效的。 该公式完全退化为返回`k`或者`k + 1`取决于比对，匹配直观的序列结构而不需要特殊处理。
