 ## 解决方案
 # 问题理解

 我们有一群聊天小组和学生。 小组会随着时间的推移而变化，因为学生可以加入和离开。 当学生在组内发送消息时，当前该组中的每个其他学生都会收到一条消息。 任务是计算每个学生在处理整个事件日志后收到的消息总数。 

输入描述了小组数量、学生数量以及按时间顺序排列的事件列表。 加入事件将学生添加到组中，离开事件将学生从组中删除，消息事件意味着一名学生向该组的其他当前成员广播消息。 输出是每个学生的一个值，表示到达该学生的消息数量。 

限制很大：最多可以有 100,000 个团体、200,000 名学生和 1,000,000 个活动。 为每条消息访问组中每个成员的直接模拟会太慢，因为单个组可以包含数十万学生，并且可能有数百万次操作。 对于一百万个事件，该解决方案需要使每个事件的时间接近恒定，从而允许大致线性的复杂性。 

棘手的部分是发送者没有收到自己的消息。 简单地计算组中发送的每条消息并将其提供给每个成员的解决方案将导致计数过多。 例如：```
1 1 1
3 1 1
```学生加入组 1 并发送消息。 正确的输出是：```
0
```如果粗心地向每个成员添加一条消息，则会输出 1。 

另一个微妙的情况是离开并随后加入同一组。 考虑：```
1 1 1
3 1 1
2 1 1
1 1 1
3 1 1
```正确的输出是：```
0
```第一条消息没有人收到，因为唯一的成员是发送者。 学生离开，然后重新加入，第二条消息具有相同的结果。 仅记住学生曾经加入过群组的解决方案可能会意外计数早期成员资格期间的消息。 

# 方法

 蛮力方法很简单。 维护每个组的成员。 当消息事件发生时，迭代该组的所有成员并增加除发件人之外的他们的答案。 这是正确的，因为它直接遵循消息传递的定义。 

当一大群人收到很多消息时，就会出现问题。 如果一个组包含 200,000 名学生并收到 1,000,000 条消息，则模拟将执行大约 2000 亿次成员更新。 数据结构操作本身没问题，但是访问次数远远超出了时间限制。 

关键的观察是，当消息发生时，我们不需要更新每个成员。 相反，每个学生稍后可以负责计算自己收到的消息。 对于特定学生和群组，他们收到的消息数是他们作为成员期间在该群组中发送的消息数减去他们在同一成员身份期间亲自发送的消息数。 

这将问题转化为跟踪成员资格的间隔。 每个活跃成员只需要两条信息：当学生加入时，群组已经收到了多少条消息，以及学生在群组中发送了多少条消息。 

对于每个组，我们存储一个全局消息计数器。 加入记录当前计数器。 离开将最终确定学生对该小组的贡献。 发送消息只会增加该组的组计数器和发送者的个人计数器。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 最坏情况下的 O(消息总数 × 组大小) | O(会员数量) | 太慢了 |
 | 最佳| O(s) | O(s) | 已接受 |

 # 算法演练

 1. 保留一个数组`group_messages`在哪里`group_messages[g]`是群组中发送的消息总数`g`。 每个消息事件只需要增加这一个值即可。 
2. 保留每个学生团体对的当前成员信息。 当学生加入小组时，存储当前值`group_messages[g]`并重置该学生在该会员期内发送的消息数。 这为计算未来接收到的消息创建了一个干净的起点。 
3. 当学生发送消息时，增加该组的消息计数器。 还要增加该组的发件人自己的已发送消息计数器，因为此消息稍后应从其接收计数中删除。 
4. 当学生离开群组时，计算会员期间群组内发生了多少条消息。 减去该学生发送的消息，然后将结果添加到该学生的最终答案中。 删除活跃会员记录。 
5. 所有事件处理完毕后，部分学生可能仍是团体成员。 以与离开事件相同的方式最终确定这些活跃成员资格，因为他们收到的消息也必须包含在答案中。 

工作原理：对于每个成员身份间隔，组计数器差异精确地计算学生属于该组时发生的所有消息。 该组中唯一学生不应收到的消息是他们自己的消息，这些消息将单独计算和删除。 每条消息都属于每个可以接收该消息的学生的一个成员资格间隔，因此不会错过任何消息或重复计数。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, s = map(int, input().split())

    group_messages = [0] * (n + 1)
    answer = [0] * (m + 1)

    active = {}

    for _ in range(s):
        t, x, y = map(int, input().split())

        if t == 1:
            active[(x, y)] = [group_messages[y], 0]

        elif t == 2:
            start, sent = active.pop((x, y))
            answer[x] += group_messages[y] - start - sent

        else:
            group_messages[y] += 1
            active[(x, y)][1] += 1

    for (x, y), (start, sent) in active.items():
        answer[x] += group_messages[y] - start - sent

    print("\n".join(map(str, answer[1:])))

if __name__ == "__main__":
    solve()
```数组`group_messages`代表每个群体的全球历史。 它永远不需要回滚，因为学生的成员资格间隔是使用他们加入时捕获的值来处理的。 

字典`active`仅存储当前存在的会员资格。 关键是一对`(student, group)`，存储的值是加入时组的消息计数以及该学生在组内发送的消息数。 

消息操作是恒定时间的。 这里很容易犯错误，因为忘记增加发送者的个人计数器，这会导致自己发送的消息被计为已接收的消息。 

最后一个循环处理从未离开小组的学生。 它们仍有未完成的成员资格间隔，因此必须在处理所有事件后关闭这些间隔。 

Python 整数就足够了，因为接收消息的最大数量可能会超过 32 位整数限制。

 # 边缘情况

 对于单成员团体情况：```
1 1 2
1 1 1
3 1 1
```学生加入唯一的组并发送一条消息。 群组计数器增加，但学生的个人发送计数器也增加。 当有效会员资格最终确定时，计算为`1 - 0 - 1 = 0`，所以答案是正确的。 

对于重复连接的情况：```
1 1 5
1 1 1
3 1 1
2 1 1
1 1 1
3 1 1
```第一消息属于第一成员资格区间并且贡献为零。 第二次连接记录新的组计数器值，因此较早的消息不会影响第二个间隔。 最终计算再次删除学生自己的消息并返回零。 

对于具有多个成员的组：```
1 2 3
1 1 1
1 2 1
3 1 1
```组计数器从 0 到 1。学生 1 记录了一条已发送的消息，而学生 2 在组中没有发送的消息。 最终确定给学生 1`1 - 0 - 1 = 0`和学生2`1 - 0 - 0 = 1`。 

对于一直分组到最后的学生，例如：```
1 2 2
1 1 1
1 2 1
```没有请假事件。 最后的清理步骤处理两个活动成员资格，就像它们在日志末尾留下一样。
