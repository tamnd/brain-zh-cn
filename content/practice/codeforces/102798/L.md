 ## 解决方案
 ## 问题理解

 我们有一系列齿轮。 一个齿轮与`t`牙齿费用`t`硬币，以及之后`k`它显示方向的时期`k mod t`。 对于选定的一组齿轮，并非每个可能的方向元组都必然可达。 问题是选择总成本最多为`b`使得可达方向元组的数量尽可能多。 我们不打印这个巨大的数字，而是打印它的自然对数。 

对于具有尺寸的齿轮`t1, t2, ...`，时钟可以显示的不同状态的数量恰好是：$$\operatorname{lcm}(t_1,t_2,\dots,t_n)$$因为在一个完整的最小公倍数周期之后，每个指针都会返回到其起始方向，并且该周期内的每个较小的时间都会产生不同的全局状态。 

预算最多是`30000`，并且最多可以有`30000`测试用例。 为每个查询单独工作的解决方案无法承担任何接近指数甚至二次的工作。 正确的方法是使用动态规划方法对所有答案进行一次预处理，直至达到最大预算`30000^2`运营。 

有少数情况很容易处理不当。 有预算`2`，选择单个 2 齿齿轮给出两种状态，所以答案是`ln(2)`。 从空产品开始但忘记始终允许一个档位的程序可能会返回零。 

对于预算`7`，选择尺寸的齿轮`3`和`4`给出 lcm 为`12`，比单个 7 齿齿轮更好。 答案是：```
7
```与输出：```
2.484906650
```总是采用最大可用装备的贪婪策略会选择`7`并失败。 

另一个陷阱是选择同一素数的多个幂。 齿轮`2`和`4`成本`6`，但他们的lcm只是`4`， 不是`8`。 最佳变换必须避免计算重复的素因子。 

## 方法

 蛮力解释是尝试每一种可能的总成本在预算范围内的齿轮集合，计算其 lcm，并保留最大的一个。 这是正确的，因为它直接检查每个有效的设计。 然而，可能的子集的数量呈指数增长。 即使只有 20 种可能的装备选择，也已经有超过一百万个子集，而且有用选择的实际数量要大得多。 

关键的观察结果是 lcm 是由素数幂构成的。 如果两个选定的齿轮包含不同的主功率`p^a`和`q^b`，用这两个素数幂替换它们可以提供相同的 lcm 贡献，同时保持较小的成本。 官方教程描述了这种简化：最优解只需要素数幂作为齿轮。 

减少之后，问题就变成了背包。 每个素数都贡献一组选择：不选择该素数的装备，或者选择其中一个`p`,`p^2`,`p^3`， 等等。 选择`p^k`添加`p^k`成本和`ln(p^k)`到答案。 这是一个分组背包，因为每个素数只能选择一个幂。 

状态存储在一定预算下可获得的最佳对数。 由于对数将 lcm 的乘法转化为加法，因此背包值转换只是加法。

 ## 算法演练

 1. 生成直到`30000`用筛子。 每个素数代表背包中的一组。 
2. 对于每个素数`p`，生成可能的齿轮`p, p², p³, ...`而该值最多为`30000`。 这些是该素数唯一有用的选择，因为取同一素数的两次幂不会增加 lcm。 
3. 将分组的背包跑过主要组。 对于每个素数，复制当前的 DP 状态并尝试添加该素数的所有可能的幂。 过渡是：$$dp[new\_cost] = \max(dp[new\_cost], dp[old\_cost] + \ln(power))$$副本是必要的，因为同一个质数不能被选择两次。 

1. 处理完所有素数后，使用预先计算的答案回答每个查询`dp[b]`。 

不变量是在处理完前几个素数后，`dp[x]`是仅使用总成本最多的那些素数可以形成的 lcm 的最大对数`x`。 每个有效选择要么跳过当前素数，要么准确选择其幂之一，因此分组转换会考虑每个可能的最佳状态。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

MAX_B = 30000

def build():
    is_prime = [True] * (MAX_B + 1)
    is_prime[0] = is_prime[1] = False
    primes = []
    for i in range(2, MAX_B + 1):
        if is_prime[i]:
            primes.append(i)
            if i * i <= MAX_B:
                for j in range(i * i, MAX_B + 1, i):
                    is_prime[j] = False

    dp = [0.0] * (MAX_B + 1)

    for p in primes:
        powers = []
        x = p
        while x <= MAX_B:
            powers.append(x)
            x *= p

        old = dp[:]
        for cost in range(MAX_B + 1):
            best = old[cost]
            for x in powers:
                if cost >= x:
                    best = max(best, old[cost - x] + math.log(x))
            dp[cost] = best

    return dp

def solve():
    dp = build()
    t = int(input())
    ans = []
    for _ in range(t):
        b = int(input())
        ans.append("{:.9f}".format(dp[b]))
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```筛子只构建素数组一次，因为所有测试用例共享相同的最大预算。 素数的幂列表仅包含有效的素数幂，因此重复的素数贡献不能进入 lcm。 

分组过渡使用`old = dp[:]`在处理素数之前。 如果没有此副本，转换可能会在一次迭代中选择同一素数的两个幂，从而产生无效的 lcm。 

浮点值在这里是安全的，因为所需的输出只是对数`1e-6`精确。 最大可能值对于 Python 浮点运算来说足够小。

 ## 边缘情况

 对于预算`1`，唯一可能的齿轮有一个方向。 DP 从零值开始，代表 lcm 为 1，因此它正确返回`ln(1)=0`。 

对于预算`6`，粗心的实施可能会选择齿轮`2`和`4`并索取 lcm`8`。 分组背包永远不允许这种转换，因为两个选择都属于素数组`2`。 它可以选择`4`， 或者`2`，但不能两者兼而有之。 

对于预算`7`，贪心选择失败，因为最大的齿轮并不总是最好的。 DP可以选择优先组`3`有价值`3`和素数组`2`有价值`4`, 生产lcm`12`，这比每个齿轮的成本最高`7`。 

对于大预算，该算法仍然有效，因为预处理仅取决于最大预算，而不取决于查询数量。 输入可以包含许多请求，但每个请求都通过直接查找来回答。
