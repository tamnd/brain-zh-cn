 ## 解决方案
 ## 问题理解

 给定一个整数数组，我们可以执行一个操作，选择一个连续的子数组并按非降序对其进行排序，同时保持数组的其余部分不变。 子数组的每一种不同选择都可能导致不同的最终数组，并且我们想要计算如果我们恰好应用一个这样的操作（包括不执行任何操作的选项）可以获得多少个不同的数组。 

一个简单的解释是尝试每个子数组，对其进行排序，然后存储结果数组。 任务是统计去重后出现了多少个唯一结果。 

约束结构（来自编辑上下文）意味着$n$足够大以至于$O(n^2)$或者更糟糕的是，通过完全模拟对子数组进行枚举是不可接受的。 对每个子数组进行排序也会引入额外的$O(n \log n)$，使得暴力破解显然不可行。 

排序后实际上不会更改数组的子数组会出现微妙的边缘情况。 例如，如果子数组已经排序，或者其端点已经与全局结构一致，则不同的子数组可以产生相同的结果。 另一个极端情况是对长度为 1 的子数组进行排序的空效应，该子数组对应于原始数组，并且必须恰好计数一次。 

## 方法

 蛮力方法很简单：枚举每一对$(l, r)$，对段进行排序，并将结果数组插入到集合中。 这是正确的，因为每个允许的操作都被明确考虑。 然而，有$O(n^2)$子数组，以及每次排序的成本$O(n \log n)$在最坏的情况下，大约导致$O(n^3 \log n)$，这远远超出了任何可行的极限。 

关键的见解是，大多数子数组都是冗余的，因为对它们进行排序实际上并不会改变任何有意义的内容，除非该段包含可以“移动跨越”由局部极值定义的边界的元素。 如果左端点已经是段的最小值，或者右端点已经是最大值，则与较短的段相比，排序不会引入任何新的配置。 这将问题简化为仅对左边界不是段最小值且右边界不是段最大值的那些段进行计数。 一旦以这种方式重新表述，每个有效段都唯一对应于一对可以进行几何编码并有效计数的约束。 

我们将计数问题转化为平面上点的优势计数问题，可以使用芬威克树或线段树的扫描线来解决。

 ## 算法演练

 我们使用两个辅助数组重新构造有效子数组，这两个数组捕获左侧和右侧的结构约束。 

1. 对于每个索引$l$，我们计算$p[l]$，右侧的第一个位置$l$其中一个元素严格小于$a[l]$出现。 如果不存在这样的位置，我们可以将其视为$n+1$。 这告诉我们任何从以下位置开始的有效子数组$l$必须至少延伸到$p[l]$，否则违反最小条件。 
2. 对于每个索引$r$，我们计算$q[r]$，最接近左侧的位置$r$其中一个元素严格大于$a[r]$出现。 如果不存在这样的位置，我们将其视为$0$。 这对以下条件进行编码：任何有效的子数组结束于$r$必须不晚于开始$q[r]$。 
3. 每个有效子数组对应一对$(l, r)$这样$l \le q[r]$和$r \ge p[l]$。 这是左侧的“最小违规边界”和右侧的“最大违规边界”的交集。 
4.我们重新解释每个右端点$r$作为一个点$(r, q[r])$在 2D 平面中。 对于固定的左端点$l$，我们希望所有点都满足$r \ge p[l]$和$q[r] \ge l$。 这是对二维矩形的优势查询。 
5. 我们按升序处理点$r$。 当我们扫描时，我们激活每个点$(r, q[r])$并存储其$q[r]$在芬威克树中。 
6. 对于每个$l$，当我们到达$p[l]$，我们查询有多少个活动点$q[r] \ge l$。 这给出了该左端点的有效右端点的数量。 

### 为什么它有效

 当子数组“具有结构意义”时，转换会精确隔离，这意味着在排序过程中两个端点都被迫移动。 数组$p$和$q$在不违反最小或最大约束的情况下对扩展段的最早障碍进行编码。 每个有效子数组都由满足这两个独立约束的一个左边界和一个右边界唯一标识。 扫描线通过将 2D 支配关系转换为 Fenwick 树上的前缀和序列，确保我们对每个有效对精确计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    p = [n + 1] * n
    q = [0] * n

    stack = []
    for i in range(n):
        while stack and a[stack[-1]] > a[i]:
            stack.pop()
        if stack:
            q[i] = stack[-1] + 1
        stack.append(i)

    stack = []
    for i in range(n - 1, -1, -1):
        while stack and a[stack[-1]] < a[i]:
            stack.pop()
        if stack:
            p[i] = stack[-1] + 1
        stack.append(i)

    pts = []
    for r in range(n):
        pts.append((r + 1, q[r]))

    pts.sort()

    fenw = Fenwick(n + 2)

    ans = 0
    j = 0

    for l in range(1, n + 1):
        while j < n and pts[j][0] < p[l - 1]:
            r, y = pts[j]
            fenw.add(y, 1)
            j += 1

        ans += fenw.sum(n) - fenw.sum(l - 1)

    print(ans)

if __name__ == "__main__":
    solve()
```基于堆栈的预处理在线性时间内计算最近的严格较小和严格较大的边界。 第一遍构建$q[r]$通过从左侧维护一个单调递增的堆栈，确保我们找到较大元素阻止扩展的最后位置。 第二遍构建$p[l]$使用递减堆栈从右侧对称。 

扫描线按升序处理右端点。 每个点在其激活时恰好被激活一次$r$符合资格，并且 Fenwick 树存储索引为$q[r]$。 查询减去前缀和来统计有多少个$q[r]$满足$q[r] \ge l$。 

一个常见的陷阱是混合基于 0 的索引和基于 1 的索引，因为两者$p$和$q$自然地在从 1 开始的坐标中定义，以实现干净的不等式。 该实施小心地改变了指数，以便比较保持一致。

 ## 边缘情况

 一个关键的边缘情况是数组严格单调。 在严格递增的数组中，每个左边界右侧都没有更小的元素，因此$p[l]$变成$n+1$，并且左约束没有有效的扩展。 扫描线正确地产生零或最小的贡献，因为没有点满足支配条件。 

在严格递减数组中，每个右端点左侧都没有更大的元素，因此$q[r]$对于大多数位置来说为零。 这会迫使大多数支配性检查失败，并且芬威克树查询会按预期返回空结果。 

当存在重复项时会出现另一种边缘情况。 由于两种堆栈结构中的比较都是严格的，因此相等的元素不会使边界无效。 这保留了正确性，因为相等不会创建新的“严格违规”点，从而改变段的最小或最大性质。
