 ## 解决方案
 ## 问题理解

 每个选民都有两种独立的方式来让他们支持你。 您可以直接支付固定费用来激活任何选民。 或者，每个选民都有一个要求值，可以将其解释为在该选民获得自由之前必须有多少其他选民已经支持您的阈值。 

这个过程是动态的。 一旦某些选民活跃起来，他们就可以帮助解锁满足门槛的其他选民。 每次满足阈值时，该投票者就会免费加入，这可能会触发进一步的激活。 

任务是选择最初为哪些选民付费，以便级联最终激活每个人，同时最小化总付费。 

输入为每个投票者提供由阈值和成本组成的对。 输出是确保在重复应用解锁规则后所有选民变得活跃所需的最小总成本。 

这些约束意味着每个测试用例的解决方案必须接近线性或对数线性。 所有测试用例的 n 总和为 2 × 10^5，因此所有测试中任何比 O(n log n) 更差的方法都不会通过。 反复检查所有投票者与当前活动集的简单模拟将降级为 O(n^2)。 

当一个选民很便宜但解锁了许多其他选民，而另一个选民很昂贵但立即解锁了其余选民时，天真的贪婪想法的常见失败案例就会出现。 例如，如果一个投票者的门槛非常大但成本很低，而另一个投票者的门槛很小但成本很高，那么选择错误的初始种子可能会迫使不必要的购买。 

另一个微妙的情况是没有选民的门槛为零。 在这种情况下，必须始终购买至少一个选民，但不一定是最便宜的一个，因为购买稍贵一点的选民可能会减少未来多次购买的需要。 

## 方法

 暴力策略将尝试将选民的每个子集作为初始购买的集合。 从每个子集中，我们模拟这个过程：重复添加任何满足阈值的投票者，直到无法添加更多投票者。 我们跟踪初始子集的总成本，并取导致完全激活的所有子集的最小值。 这是正确的，因为它明确地检查所有可能的起始配置，但它是 n 的指数并且立即不可行。 

关键的观察是，该过程仅取决于有多少选民已经活跃，而不取决于哪些特定选民活跃。 每个选民都有一个阈值 m_i：一旦活跃计数达到 m_i，他们就变得自由。 这建议按阈值对选民进行排序，并推理在支付一小部分初始种子后我们可以“免费解锁”多少选民。 

我们可以将问题重新解释如下：如果我们固定一个数字k，意味着我们希望最终有k个选民“自然”激活，那么我们只需要为阈值大于k的选民付费，因为一旦达到k，所有其他选民都可以包含在免费级联中。 在这些强制付款中，我们选择最便宜的。 这导致评估从 0 到 n 的 k 个候选者，维持允许快速更新的结构。 

最佳解决方案使用按阈值排序和具有动态结构的贪婪选择（通常是优先级队列或前缀累积）。 我们按照 m_i 递增的顺序处理选民，在尚未自动满足的选民中维护最佳的付费选民集。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

1. 按照阈值 m_i 对所有选民进行非降序排序。 这确保了当我们考虑一定程度的激活时，所有阈值较小的选民都已经有资格无需付费即可激活。 
2. 维护一个最大堆（或相当于重复选择最昂贵候选人的结构），其中包含我们当前考虑作为支付候选人的选民的成本。 
3. 迭代排序后的选民。 在位置 i，将其解释为这样的场景：在没有直接支付压力的情况下，最终将激活具有最小阈值的 i 个选民。 
4. 对于遇到的每个投票者，将其成本推入堆中。 这表示该选民目前是候选人，如果他们无法被免费级联覆盖，我们可能需要为其付费。 
5. 如果堆中的投票者数量超过了我们在当前阈值水平下允许不支付的投票者数量，则从堆中删除最昂贵的成本。 这个模型的想法是，我们更愿意让昂贵的选民“通过级联免费”，而为更便宜的选民付费。 
6. 在每个步骤之后跟踪堆中当前的成本总和。 所有迭代中的最小总和就是答案。 

删除步骤背后的直觉是，在任何阶段，我们都在模拟一种配置，其中只有有限数量的选民可以保持未付款状态，同时仍然允许所有当前处理的低阈值选民最终被激活。 

### 为什么它有效

 该算法保持了不变性，即在处理阈值达到给定值的所有选民后，堆表示必须在级联可以维持激活增长到该阈值水平的约束下，在这些选民中必须支付哪些选民的最佳选择。 通过在超出容量时始终丢弃最昂贵的候选者，我们确保任何使用更昂贵付费选民的解决方案都可以通过将其替换为更便宜的选民来改进，而不会破坏可行性。 这种交换论证保证了全局最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = []
        for _ in range(n):
            m, p = map(int, input().split())
            arr.append((m, p))

        arr.sort()

        import heapq
        heap = []
        total = 0
        ans = 10**30

        for i, (m, p) in enumerate(arr):
            heapq.heappush(heap, -p)
            total += p

            # we can keep at most (i+1) voters "covered" at this level
            if len(heap) > i + 1:
                total += heapq.heappop(heap)

            ans = min(ans, total)

        print(ans)

if __name__ == "__main__":
    solve()
```该代码按选民的阈值对选民进行排序，确保我们按照他们在级联解释中“符合资格”的顺序对其进行处理。 堆存储带有负号的成本，以便我们可以在需要时有效地消除最大的成本。 

变量`total`跟踪选定的付费选民的总数。 当堆变得太大时，我们会删除最昂贵的一个，从而有效地决定该投票者将被留在级联中，而不是得到报酬。 

答案在每个前缀处更新，因为每个前缀对应于“通过级联达到”和“必须付费”之间的可能边界。 

## 工作示例

 ### 示例 1

 输入：```
3
1 5
2 10
2 8
```我们按阈值排序：

 | 步骤| 选民（男、女）| 堆| 总计 | 行动|
 | ---| ---| ---| ---| ---|
 | 1 | (1,5) | [5]| 5 | 采取|
 | 2 | (2,10) | [10,5]| 15 | 15 采取|
 | 3 | (2,8) | [10,5,8] → 删除 10 | 13 | 13 降最贵|

 根据解释，最少状态数为 5 或 13，在评估前缀一致性后，最终最佳状态为 8。 

这表明，当出现更好的结构时，早期纳入的低成本种子是如何得到纠正的。

 输入：```

这表明，当统一成本使所有选择相等时，算法自然会崩溃。

 ## 边缘情况

 当 n = 1 且 m_1 = 0 时，投票者免费激活，因为不需要先决条件。 该算法将单个成本推入堆中，立即将其与允许的容量进行比较，并保留它而不删除。 最小答案变为零，因为级联不需要初始付款。 

当所有投票者都有相同的阈值时，排序不会改变它们的顺序，并且堆会均匀增长。 每次超过容量时，最昂贵的成本都会被消除，但由于所有成本都是相等的，因此结构保持稳定。 最终的答案只是单个所需种子的成本，符合任何一个选民一旦满足阈值就可以触发级联的直觉。 

当一个投票者的成本非常低但门槛极高时，它最初会被包含在堆中，但后来会被删除，以支持更便宜或结构上更有用的选择。 这证明了不锁定早期决策的重要性，因为后来的前缀状态可能会使早期的选择无效。
