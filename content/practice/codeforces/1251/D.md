 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 在每个场景中，都有奇数个员工，每个员工都有一个工资区间，必须从中选择他们的最终工资。 我们还获得了一份总预算，保证足以向每个人支付最低工资。 

任务是在允许的区间内为每个员工分配工资，以使所有选定工资的中位数尽可能大。 中位数是在对所有工资进行排序后定义的，由于员工人数为奇数，因此它是单个中间元素。 

因此，问题不在于在任何全球意义上最大化总工资或公平。 它是将排序后的薪资数组的中间元素尽可能推高，同时仍然尊重个人界限和全球预算。 

关键的相互作用在于三个约束之间：每个薪水都有一个区间，所有薪水的总和是有限的，并且只有中间位置很重要。 

这些约束足够大，任何尝试模拟分配或通过每次猜测构造完整数组来重复检查可行性的解决方案都会失败。 总共有多达 2×10^5 名员工，任何比每个测试用例的 O(n log n) 更差的方法都将无法扩展。 

当许多间隔很宽但预算却超出最小总和时，就会出现微妙的边缘情况。 简单地独立提高所有工资的天真贪婪将会失败，因为增加一个值可能会迫使降低其他地方的可行性，即使下限可行性得到保证。 

如果我们试图以对称的方式贪婪地向每个人分配更高的工资，就会出现另一种失败模式。 这忽略了只有中间位置很重要，因此没有必要在下半部分浪费预算。 

## 方法

 蛮力的想法是尝试中位数的所有可能值并检查是否可以实现。 对于候选值 x，我们将尝试构建一个分配，其中至少一半的员工的工资至少为 x，同时尊重时间间隔和总预算。 

为了验证固定 x 的可行性，我们需要贪婪地分配工资：将尽可能多的人推到他们的区间内至少 x，然后分配剩余的预算。 每次检查的复杂度可以为 O(n)。 

然而，中位数可以大到 10^9，因此不可能对所有可能的值进行线性扫描。 即使二分查找 x 每个测试用例的复杂度为 O(n log n)，如果每次检查都没有仔细优化，则速度太慢，并且仍然存在员工总数低于 2×10^5 的严格限制。 

关键的观察结果是可行性在 x 中是单调的。 如果我们能让至少k名员工的工资≥x，那么任何较小的x也是可行的。 这允许对答案进行二分搜索。 

第二个也是更深入的见解是如何有效地评估可行性。 我们不需要完全构造一个作业。 我们只需要知道是否可以强制至少 k = n//2 + 1 名员工达到至少 x，同时保持在预算范围内。 

对于每个员工来说，存在与x相关的三种相关状态：他们无法达到x（r_i < x），他们只能通过支付额外费用才能达到x（l_i < x ≤ r_i），或者他们已经被迫高于x（l_i ≥ x）。 我们贪婪地决定将哪些员工推到x以上，总是更喜欢那些最便宜的员工，因为预算是限制因素。 

这将可行性检查转变为根据将候选者提升到 x 的成本对候选者进行排序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力构造| O(n·最大工资) | O(n) | 太慢了|
 | 二分查找+贪心可行性| O(n log n log A) | O(n log n log A) | O(n) | 已接受 |

 ## 算法演练

 我们对答案进行二分查找，将中值 x 作为阈值。

1. 固定候选中值 x，并根据每个员工相对于 x 的区间对他们进行分类。 如果 r_i < x，则该员工无法为达到中位数做出贡献，因此他们将被忽略为“高组”。 如果 l_i ≥ x，则它们已经满足条件，无需额外成本。 否则，可以选择将它们推送到 x，成本为 x - l_i。 
2. 计算有多少员工已经满足 l_i ≥ x。 这些人自动成为高级群体的一部分。 如果这个数字已经至少是 k = n//2 + 1，那么 x 是可行的，因为我们可以在不影响中位数的情况下最少地分配其他人。 
3. 如果没有足够的员工达到 x 以上，我们将收集所有“可升级”的员工，即 l_i < x ≤ r_i 的员工。 对于它们中的每一个，计算成本 = x - l_i。 
4. 按升序对这些成本进行排序。 我们希望首先选择最便宜的员工进行升级，因为每次升级都会多贡献一个等于或高于 x 的人员。 
5. 我们采取最小的成本，直到达到高组中的 k 名员工。 如果我们在达到 k 之前用完所有候选者，则 x 是不可行的。 
6. 对于那些选定的升级，将总额外成本计算为 (x - l_i) 之和。 如果这个增加的成本超过了支付所有l_i后的剩余预算，那么x是不可行的； 否则是可行的。 
7. 在足够大的范围内二分搜索 x，通常最大为 10^9。 

正确性依赖于这样一个事实：固定 x 的任何最佳解决方案都不会浪费预算，将某个人增加到超出满足中值条件所需的 x 之上。 任何额外的增加都无助于可行性，只会增加成本。 

### 为什么它有效

 对于固定的阈值x，唯一重要的是在预算约束下是否可以使至少k个工资≥x。 在挑选 k 名员工晋升到 x 以上的所有方法中，最便宜的选择始终是选择 (x - l_i) 最小的员工。 任何偏离此选择的行为只会增加总成本，而不会增加可行性。 这种贪婪结构确保可行性检查在 x 中是最优且单调的，这使得二分搜索有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(x, arr, s, k):
    base = 0
    candidates = []

    for l, r in arr:
        base += l
        if r < x:
            continue
        if l >= x:
            continue
        candidates.append(x - l)

    if base > s:
        return False

    need = k
    have = 0

    for l, r in arr:
        if l >= x:
            have += 1

    if have >= k:
        return True

    need = k - have

    candidates.sort()

    extra = 0
    for i in range(min(need, len(candidates))):
        extra += candidates[i]

    return base + extra <= s

def solve():
    t = int(input())
    for _ in range(t):
        n, s = map(int, input().split())
        arr = [tuple(map(int, input().split())) for _ in range(n)]
        k = n // 2 + 1

        lo, hi = 1, 10**9
        ans = 1

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(mid, arr, s, k):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案围绕可行性检查器和二分搜索驱动程序构建。 可行性函数计算向所有员工支付最低工资的基准成本，然后尝试“升级”足够的员工以达到中位数阈值。 

关键细节是将员工分为已经达到或高于 x 的员工和可以升级的员工。 排序步骤确保我们始终首先选择最便宜的升级。 

二分搜索驱动解决方案，因为可行性是单调的：如果可以实现中值 x，则也可以实现任何较小的值。

 ## 边缘情况

 当许多员工已经具有 l_i ≥ x 但不需要中位数时，就会出现一种棘手的情况。 该算法正确地将他们视为高组的“免费”贡献者，即使他们可能不是最便宜的升级候选者之一。 由于它们已经在没有成本的情况下满足了阈值，因此它们永远不会进入候选列表，并且不会扭曲贪婪选择。 

另一个边缘情况是最便宜的升级数量不足以达到 k。 在这种情况下，候选列表在满足中值要求之前就用完了，并且可行性在不尝试不必要的总和的情况下提前失败。
