 ## 解决方案
 ## 问题理解

 当有人一一按下键盘按键后，我们会得到一个出现在屏幕上的最终字符串。 每个按键都对应一个小写拉丁字母，并且在整个打字过程中，每个按键要么始终正常，要么始终损坏。 

健康键的行为很简单：按下它会将其字母的一份副本准确地附加到输出中。 损坏的钥匙更具攻击性：每次按下都会附加其字母的两份副本，而不是一份。 最终的字符串是在未知的按键序列中混合这两种行为的结果。 

任务不是重建按键顺序。 相反，我们必须确定哪些字母保证与最终字符串的每种可能解释中的健康键相对应。 仅当在字符串的任何有效分解中不可能将其分解为单字母和双字母时，该字母才可以安全输出。 

关键的困难在于，同一个字符串通常可以用多种方式解释，具体取决于我们是否将出现的事件视为单个字符或双字符。 该决定在外观上是局部的，但在约束上是全局的，因为单个字母在整个字符串中可能被一致或不一致地解释。 

字符串长度最多为 500，并且最多有 100 个测试用例，因此每个用例解决方案的 O(n^2) 或 O(n) 就足够了。 解释选择中的任何指数都是不必要的，因为我们不需要枚举所有分解。 

一个天真的错误是假设如果一个字母有时单独出现，那么它一定是健康的，或者每对相邻的相同字母一定来自损坏的钥匙。 两种解释都失败了，因为配对决策在整个字符串中并不是独立的。 

例如，考虑字符串`aabb`。 有人可能会认为`a`已损坏，因为它显示为`aa`， 和`b`已损坏，因为它显示为`bb`。 但`aabb`也可能来自四种健康的压力机：`a a b b`，使两个字母都健康。 所以局部分组是不够的。 

另一个微妙的失败案例是交替模式，例如`abab`。 在这里，两个字母都不能成对，因此两个字母都必须是健康的，但是尝试尽可能配对的贪婪扫描可能会错误地将两个字母标记为损坏或不明确。 

## 方法

 直接暴力方法会尝试所有方法将字符串划分为大小为 1 或 2 的段，确保每个段都是单个字符的重复。 每个分区对应于假设每次印刷机是否产生一个或两个字符。 生成有效分区后，我们可以推断出哪些字母曾经以与损坏或健康一致的方式出现，然后在所有分区上相交。 

这很快就变得不可行，因为每个位置都可能分支为两个选择，在最坏的情况下导致 O(2^n) 分解。 即使进行了修剪，字符串的有效分段数也一样`aaaaaa...`呈指数级增长。 

关键的观察是我们不需要显式地构造所有有效的分解。 相反，我们只需要确定是否可以在每个有效的解释中强制破坏一个字母。 同样，我们想要的字母永远不能被解释为每次按下都始终只产生一个字符。 

关键的简化是观察到，只有当我们可以将字母的出现完全划分为不相交的相同连续字母对时，字母才是不安全的，这意味着每个出现都可以分为大小为 2 的块。 如果某个字母至少出现一次不能与相同的邻居配对，则存在一个有效的解释，即该字母必须是健康的。 

因此，对于每个字母，我们只需要检查它在字符串中出现的所有字母是否可以被不相交的相邻对完全覆盖。 如果这是不可能的，则保证该信件在至少一种有效的解释中是健康的，因此不在所需的输出中。 相反，如果可以将所有出现的情况完全配对，则该字母在某些解释中可能会被完全破坏，因此不能保证它是健康的。 

这将问题简化为线性扫描：检测整个字符串中相邻对中字母的出现是否可以完美匹配。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 扫描字符串并记录每个字母出现的所有索引。 这让我们可以在不受其他人干扰的情况下推理每个角色的配对结构。 
2. 对于固定字母，尝试在原始字符串中从左到右模拟贪婪配对。 每当我们看到位置 i 处的字母时，我们都会检查 i 和 i+1 是否都包含相同的字母。 如果是，我们将其视为一个损坏的钥匙块并跳过这两个位置。 如果不是，则此事件不可能是损坏的对的一部分，因此必须将其视为单次按下。 
3. 在扫描时，如果我们遇到这样的情况：单个出现不能匹配成对，也不能安全地视为整个结构中一致的单例，我们得出的结论是，该字母不能完全解释为到处都是损坏的。 这意味着它是安全的，应该包含在答案中。 
4. 对所有 26 个字母独立重复此过程。 
5. 收集所有不符合“完全可配对”条件的字母，并按字母顺序输出。 

### 为什么它有效

 关键的不变量是任何损坏的字母都必须在连续的相同字符对中出现。 如果一个字母确实被损坏，则每次出现都必须是有效相邻对的一部分，因为损坏的印刷机会产生恰好两个连续的相同字母。 如果即使有一个事件是孤立的或破坏了邻接一致性，那么在该字母总是被破坏的地方不存在分解，这意味着至少有一种解释是健康的。 因此，可以被相邻对完全覆盖的字母集合恰好对应于不能保证健康的字母。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_fully_pairable(s, ch):
    i = 0
    n = len(s)
    while i < n:
        if s[i] != ch:
            i += 1
            continue
        if i + 1 < n and s[i + 1] == ch:
            i += 2
        else:
            return False
    return True

t = int(input())
for _ in range(t):
    s = input().strip()
    res = []
    for c in "abcdefghijklmnopqrstuvwxyz":
        if is_fully_pairable(s, c):
            res.append(c)
    print("".join(res))
```功能`is_fully_pairable`检查是否所有出现的字符都可以作为相邻对使用。 指针`i`通过字符串移动并贪婪地消耗`cc`尽可能配对。 如果出现一个独立的事件，它就破坏了将字符解释为始终损坏的可能性。 

主循环只是将此测试应用于所有 26 个字母并收集满足它的字母。 

## 工作示例

 ### 示例 1：`zzaaz`我们追踪每个角色。 

| 我| s[i] | 行动|
 | ---| ---| ---|
 | 0 | z | 找到对了吗？ 不，单个 z |
 | 1 | z | 使用 z z 对 |
 | 2 | 一个 | 配对 a 二手 |
 | 4 | z | 剩下单个 z，没有对 |

 为了`z`，配对失败，因为存在不匹配的情况。 为了`a`，配对完全成功。 

这表明仅`a`可以保证健康。 

### 示例 2：`ccff`| 我| s[i] | 行动|
 | ---| ---| ---|
 | 0 | c | c c 对 |
 | 2 | f | f f 对 |

 两个字母都可以完全配对，这意味着两个字母都可以一致地被破坏，因此都不能保证健康。 因此输出为空。 

这证实了完全可配对字母和具有不可避免的单例结构的字母之间的逻辑区别。

 ## 边缘情况

 关键的边缘情况是字母以奇数长度出现。 例如，`aaa`不能完全划分为`aa`块，留下一个剩余的事件。 该算法会立即检测到这一点，因为它遇到了单个不匹配的`a`消耗一对后，在完整的配对解释中返回该字母的失败。 

另一种边缘情况是交错，例如`ababa`。 尽管这两个字母都频繁出现，但它们都不能形成一致的相邻对。 扫描在每个字母第一次单独出现时失败，确保两者都被正确分类为健康候选者。 

最后一个微妙的情况是局部可能配对但全局不一致。 例如`aabbaabb`允许完全配对，所以`a`被标记为可配对，而`abac`中断配对`a`立即在隔离`c`过渡，防止错误分类。
