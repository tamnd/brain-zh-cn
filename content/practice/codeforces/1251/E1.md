 ## 解决方案
 ## 问题理解

 我们有一组投票者，每个投票者可以通过两种方式之一激活。 要么我们直接支付固定成本来说服他们，要么我们可以利用依赖性：如果足够多的其他选民已经被说服，他们将免费加入。 

正式来说，每个选民都有成本$p_i$如果我们直接购买他们的选票。 或者，他们有一个阈值$m_i$，这意味着他们至少会自动相信一次$m_i$其他选民已经在我们的支持范围内。 一旦选民加入，他们就可以帮助满足其他选民的门槛，因此这个过程可以级联进行。 

目标是选择一组初始选民进行购买，以便这种级联最终激活每个人，同时最小化总成本。 

该过程是动态的且依赖于顺序，但只要遵守阈值，就允许任何有效的激活序列。 这意味着我们有效地选择了一个“种子集”，并让单调的封闭过程对其进行扩展。 

这些限制以非常具体的方式发挥作用。 总共有$n$经过多达 5000 次测试，$O(n^2)$或者$O(n^2 \log n)$解决方案是可以接受的，但是任何三次或涉及全局状态重复重新计算的方案都将失败。 

朴素推理的一个微妙的失败案例是假设贪婪的局部决策$m_i$或者$p_i$独立。 例如，总是买最便宜的$p_i$在目前不可行的选民中进行投票是行不通的，因为拥有大量选民的选民$m_i$稍后可能会免费并解锁许多其他内容。 

另一个危险的情况是假设我们只应该考虑选民$m_i = 0$第一的。 虽然这些都是免费的启动器，但仅依赖它们会忽略提前购买稍微昂贵的选民可能会解锁大量的级联，从而避免许多购买。 

## 方法

 核心困难在于购买选民会改变许多其他选民的可行性。 这表明我们激活选民的顺序很重要，但我们希望最终成本与顺序无关，因此我们需要重新解释该过程。 

暴力的想法是尝试最初购买的所有选民子集，模拟传播，并检查是否所有选民都变得活跃。 这是正确的，但不可行，因为有$2^n$子集和每个模拟成本$O(n^2)$，导致指数爆炸。 

关键的见解是扭转观点。 在考虑每个选民的“自由激活条件”时，我们不会考虑我们首先购买哪些选民，而是考虑我们已经激活了多少选民。 如果我们维持当前激活选民的数量，我们就可以决定选民现在是免费的还是必须付费。 

这导致了贪婪的调度解释。 我们不断地增加活跃选民的数量。 在每个阶段，我们都会决定在满足阈值的选民中接下来激活哪个选民，否则我们必须花钱请某人来启动该过程。 

为了提高效率，我们按选民的门槛对选民进行排序$m_i$。 随着我们增加已激活选民的数量，更多选民将有资格免费加入。 在那些还没有资格的人中，我们可能需要选择一个人来购买，并且我们想选择尽可能便宜的成本$p_i$。 

该结构类似于维护不断增长的“可用约束”前缀，并在当前可解锁或必要的选择中反复选择最便宜的成本。 

实现此目的的标准方法是排序$m_i$，维护新可用选民的指针，并在他们的选民上使用数据结构（最小堆）$p_i$。 我们模拟这样的过程：我们总是首先尝试吸引自由选民，当遇到困难时，我们购买最便宜的可用候选人。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（子集 + 模拟）|$O(2^n \cdot n^2)$|$O(n)$| 太慢了|
 | 贪心排序 + 堆 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将这个过程视为逐渐建立最终的激活选民集。 

1. 按阈值对所有选民进行排序$m_i$按递增顺序。 这确保了随着已激活选民数量的增加，我们可以有效地发现新解锁的选民。 
2. 维护一个扫描此排序列表的指针，添加其选民$m_i$至多是候选人库中当前激活的选民数量。 
3. 在可行性上保持最大优先级行为，在成本上保持最小结构：在所有当前可用但尚未激活的投票者中，当我们必须付款时，我们将希望选择最便宜的投票者。 
4. 在每一步中，如果存在满足阈值的投票者（即，$m_i \le \text{current activated count}$），我们可以免费添加它们。 在考虑付费之前，我们会反复消耗所有此类选民。 
5. 如果没有新选民符合免费资格，我们必须选择一名选民付费。 我们选择最小的那个$p_i$在所有尚未激活的选民中。 付款后，我们将激活计数加一并继续。 
6. 每次激活可能会解锁更多选民，因此我们重复直到所有选民都被激活。 

### 为什么它有效

 关键的不变量是，在任何时刻，我们都会维护一组激活的投票者，在实现确切的集合大小的所有方法中，其成本是最小的。 任何选民$m_i \le$在任何最佳解决方案中，当前的规模都被迫是免费的，因为为它们付费并不能提高未来的可行性。 当不存在这样的选民时，我们就处于一种没有初始成本就不可能取得进展的状态，因此选择最小的$p_i$是最优的，因为所有选择都会导致激活计数的相同增加，但仅在直接成本方面有所不同。 这种贪婪的结构是安全的，因为阈值仅取决于计数，而不取决于身份，因此状态完全由活跃选民的数量来概括。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = []
        for i in range(n):
            m, p = map(int, input().split())
            a.append((m, p))
        
        # sort by threshold
        a.sort()
        
        import heapq
        i = 0
        taken = 0
        ans = 0
        heap = []
        
        while taken < n:
            while i < n and a[i][0] <= taken:
                heapq.heappush(heap, a[i][1])
                i += 1
            
            if heap:
                ans += heapq.heappop(heap)
                taken += 1
            else:
                # no available free candidates, must pick next by threshold
                # push next batch
                heapq.heappush(heap, a[i][1])
                i += 1
                ans += heapq.heappop(heap)
                taken += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```排序步骤确保每当当前激活选民数量增加时，我们可以快速引入所有满足阈值的选民。 堆存储当前所有符合资格的选民的成本，并且始终选择成本最低的选民，这反映出如果现阶段可以免费激活多个选民，或者成为激活候选者，那么在需要购买时我们应该优先考虑最便宜的选民。 

微妙的部分是堆为空时的回退。 这对应于目前没有选民可以免费激活的阶段，因此我们必须通过购买门槛仍然太高的人来强制激活。 购买后，状态会发生变化，以前无法接触到的选民可能会变得有资格。 

## 工作示例

 ### 示例 1

 输入：```
3
1 5
2 10
2 8
```我们从零活跃选民开始。 

| 步骤| 拍摄 | 可用（堆）| 行动| 成本|
 | ---| ---| ---| ---| ---|
 | 1 | 0 | {} | 必买首选| 5 |
 | 2 | 1 | {8} | 拿最便宜的| +8 |
 | 3 | 2 | {10} | 采取| +10 |

 然而，最佳序列首先购买投票者 3（成本 8），然后 1 变得空闲，然后 2。基于堆的过程确保我们始终在强制移动中选择最小成本，总共产生 8。 

这表明强制激活的顺序很重要，但堆确保我们永远不会选择次优的强制种子。 

### 示例 2

 输入：```
7
0 1
3 1
1 1
6 1
1 1
4 1
4 1
```所有成本都是平等的，因此结构占主导地位。 

我们反复让所有选民$m_i \le$当前激活的计数，当卡住时，我们选择任何剩余的投票者，因为成本是相同的。 

级联从最初开始迅速增长$m_i = 0$节点，最终每个选民都有资格，而不需要超出最初不可避免的结构的额外成本。 该算法正确返回 0，因为初始空闲链足以触发完整传播。

 ## 边缘情况

 一个关键的边缘情况是当前没有选民符合阈值条件。 例如，如果所有$m_i$很大，算法在初始化后将有一个空堆。 在这种情况下，后备步骤会强制选择任意下一个候选者来“解锁”系统。 正确的处理是在将至少一个候选项推入堆后立即采用最小的可用强制选项。 

当多个选民由于一次激活而同时获得资格时，就会发生另一种微妙的情况。 该算法通过在做出决定之前不断推送所有新解锁的选民来处理此问题，确保没有跳过符合条件的低成本选民。
