 ## 解决方案
 ## 问题理解

 我们有一棵城市树，每个城市都有人口。 这些道路连接着城市，因此任何两个城市之间都只有一条简单的路径。 乐队希望沿着某条路径在一系列城市演出，音乐会举办城市的人口严格增加。 目标是最大化音乐会的数量，这意味着沿着树中任何路径的城市人口的最长严格递增子序列。 

输入给出了城市数量、人口以及连接城市的道路列表。 输出是一个整数：可能的最大音乐会数量。 

树结构意味着没有循环，并且因为$n$可以达到 6000，二次或三次复杂度的算法是可行的，但任何更糟糕的（比如$O(n^4)$）立刻就太慢了。 每个城市的人口最多可达$10^6$，因此仅当我们使用映射时，简单的基于值的索引才是可能的，但大小为 10^6 的直接数组是浪费的。 我们还必须考虑到多个城市可以拥有相同的人口。 

一个微妙的边缘情况是，一条路径上的几个城市拥有相同的人口。 由于序列必须严格递增，因此两个相同的群体不能同时举办音乐会。 另一种边缘情况是星形树，其中一个中心节点连接到许多叶子； 仅查看单个分支的天真的 DFS 可能会错过从一个叶子经过中心到另一叶子的最佳路径。 

例如，考虑由三个城市组成的树： 人口`[1, 2, 1]`有边缘`1-2, 2-3`。 最优序列是`[1, 2]`或者`[2, 3]`有 2 场音乐会，而不是 3 场，因为序列必须严格递增。 

## 方法

 暴力方法将枚举树中的每条简单路径，为每条路径生成城市人口的所有子序列，并跟踪最长的严格递增序列。 有$O(n^2)$树中的路径，每条路径最多有$n$城市，大致给出$O(n^3)$要考虑的序列。 在每个路径内生成子序列使得这种方法在每个路径上呈指数增长，这对于$n = 6000$。 

关键的观察结果是，问题简化为计算树中路径上的最长递增子序列 (LIS)。 如果我们将每个节点视为潜在的根，并通过动态规划将 LIS 信息传播到其子节点，我们就可以避免枚举所有路径。 由于树没有循环，DFS 允许我们通过将每个节点的种群与子节点的种群进行比较来计算从每个节点开始的 LIS。 每个城市只需要知道，对于给定的人口，如果最后一场音乐会是针对该人口举行的，则音乐会的最大数量。 这给出了一个$O(n^2)$算法，这是可以接受的$n = 6000$。 

我们可以通过仅存储以每个城市结束的最大 LIS 并合并父节点和子节点之间的信息来进一步优化。 这避免了从头开始为每对城市重新计算 LIS。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * n^2) | O(2^n * n^2) | O(n^2) | O(n^2) | 太慢了 |
 | 树 DP / LIS 传播 | O(n^2) | O(n^2) | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 1. 读取城市和人口的数量，并根据道路连接构建树的邻接表。 邻接列表允许在 DFS 期间快速遍历邻居。 
2.初始化DP表`dp[u][v]`存储从节点开始的路径上音乐会的最大数量`u`并以节点结束`v`，最后一场音乐会在`v`。 由于我们只关心严格递增的序列，因此仅当下一个节点群体大于最后一个协调群体时，我们才会传播 LIS 信息。 
3. 从每个节点执行DFS`u`作为起点。 对于每个邻居`v`的`u`还没有被访问过，递归计算以`v`。 如果`r[v] > r[u]`，我们可以通过在以下地点举办音乐会来扩展 LIS`v`。 使用找到的最大长度更新 DP 表。 
4. 在 DFS 期间传播值时，保持全局最大值`answer`跟踪所有起点上发现的最大数量的音乐会。 每次更新 DP 值时，将其与`answer`并进行相应更新。 
5. 所有节点的DFS完成后，`answer`包含乐队可以沿着树中的任何路径表演的最大音乐会数量。 

工作原理：DFS 确保我们探索所有路径而无需重新访问城市，而 DP 表保证对于以给定最后音乐会人口的城市结束的每条路径，我们存储可实现的最大音乐会数量。 由于树没有循环，因此不会错过任何路径，并且每一步都强制执行严格递增条件。 合并子节点的 DP 值可确保我们考虑每个节点的向上和向下路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10000)

n = int(input())
r = list(map(int, input().split()))
adj = [[] for _ in range(n)]
for _ in range(n-1):
    a, b = map(int, input().split())
    adj[a-1].append(b-1)
    adj[b-1].append(a-1)

dp = [1] * n  # dp[u]: max concerts ending at u
answer = 1

def dfs(u, parent):
    global answer
    for v in adj[u]:
        if v == parent:
            continue
        dfs(v, u)
        if r[v] > r[u]:
            dp[v] = max(dp[v], dp[u] + 1)
            answer = max(answer, dp[v])

for i in range(n):
    dfs(i, -1)

print(answer)
```解决方案首先建立邻接表并初始化一个DP数组`dp`代表在每个城市结束的最大音乐会数量。 从每个城市作为根执行 DFS，确保我们探索从该节点开始的所有路径。 在 DFS 期间，只允许严格增加转换，这强制执行了协奏曲规则。 这`answer`每当发现更长的序列时，变量就会更新。 增加了递归限制以处理接近 6000 个节点上限的深度树。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n^2) | O(n^2) | 每个节点发起一个可以访问所有其他节点的 DFS，每条边更新 DP 的复杂度为 O(1)。 当 n ≤ 6000 时，n^2 ≤ 36,000,000 次操作符合 5 秒的时间限制。 |
 | 空间| O(n^2) | O(n^2) | DP数组的大小为n； 邻接表为 O(n)； 递归堆栈最多为 n。 适合 256 MB 限制。 |

 这确保了算法在允许的最大输入大小下高效运行。
