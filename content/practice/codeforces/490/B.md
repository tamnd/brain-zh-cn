 ## 解决方案
 ## 问题理解

 每个输入行描述一名学生，但不会直接给出该学生自己的 ID。 相反，我们被告知站在他们前面的学生的 ID 和站在他们后面的学生的 ID。 由于每个学生在队列中只出现一次，因此这些邻居关系完全确定了一条链。 

如果学生前面没有人，则前面的 ID 为`0`。 那个学生是队列中的第一个人。 如果学生后面没有人，则后面的 ID 为`0`。 那个学生是队列中的最后一个人。 

挑战在于记录是以任意顺序给出的。 我们必须重建从第一个学生到最后一个学生的整个队列。 

学生人数多达`2 · 10^5`。 任何重复扫描所有学生寻找下一个学生的算法都需要大约`n²`工作。 和`n = 200000`，这会变成大约 400 亿次操作，远远超出了两秒的限制。 我们需要接近线性时间的东西。 

ID 本身可以大到`10^6`，所以我们不能使用按学生 ID 索引的数组。 哈希图是自然的选择。 

这个问题的棘手部分是队列不是通过简单地跟随第一个元素的“下一个”指针来重建的。 输入仅给出对`(front, back)`。 我们必须首先发现这些关系如何编码实际的顺序。 

考虑这个小队列：```
10 20 30
```记录是：```
0 20
10 30
20 0
```粗心的实现可能会将第二个数字视为下一个元素并输出：```
20 30
```因为它从记录开始`front = 0`。 实际的第一个学生是`10`，它从未明确出现在该记录中。 正确恢复学生身份是主要挑战。 

另一个微妙的情况是队列在奇数位置和偶数位置之间交替。 例如：```
1 2 3 4 5
```公认的解决方案使用的重建方法首先构建奇数位置，然后填充偶数位置。 如果该结构没有被正确理解，很容易产生：```
1 3 5 2 4
```其中包含所有学生，但不按队列顺序排列。 

## 方法

 暴力解决方案从第一个学生开始，反复搜索所有记录以找出下一个学生。 由于有`n`位置和每次搜索可能会检查`n`记录，最坏情况的复杂度是`O(n²)`。 

为了`n = 200000`，这大约意味着：```
200000 × 200000 = 4 × 10^10
```运营。 

这太慢了。 

为了找到更快的方法，我们需要了解隐藏在输入中的结构。 

设学生的记录为`(a, b)`， 在哪里`a`是前面的 ID 和`b`就是后面的ID。 

假设学生`x`站在队列的某个地方。 然后：```
a <- x -> b
```后面的学生`x`是`b`。 

现在查看属于学生的记录`b`。 它的前邻居必须是`x`。 

这意味着映射```
x -> b
```可以从关系式中恢复：```
front_of[b] = x
```公认的解决方案以稍微不同的方式存储信息。 

定义：```
next[a] = b
```对于每条记录`(a, b)`。 

对于队列```
p1 p2 p3 p4 p5 ...
```此映射将每个奇数位置学生链接到下一个奇数位置学生：```
p1 -> p3 -> p5 -> ...
```当学生时`0`第二个位置的链接：```
0 -> p2 -> p4 -> ...
```这将创建两个交错的链。 

关键的观察是第一个学生的前邻居是`0`。 一旦我们知道第一个位置，沿着奇数位置链重建所有奇数位置。 跟随链条从`0`重建所有偶数位置。 

知道两个链后，我们将它们交错以恢复原始队列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读每一对`(a, b)`。 
2. 存储关系：```
next[a] = b
```这是公认的解决方案所使用的核心结构。 
3. 检测第一个学生。 

第一个学生的前邻居等于`0`。 如果一条记录是`(0, x)`，那么该记录所描述的学生就是队列中的第一个人。 
4. 创建一个长度为answer的数组`n`。 
5. 让第一个学生就位`0`。 
6. 首先填充奇数队列位置。 

从第一个学生开始，反复遵循：```
current = next[current]
```并将拜访的学生安置在以下位置：```
0, 2, 4, 6, ...
```这些正是原始队列的奇数位置（使用基于一的索引）。 
7. 填充偶数队列位置。 

开始于：```
current = next[0]
```并将拜访的学生安排到以下位置：```
1, 3, 5, 7, ...
```这些形成了原始队列的偶数位置。 
8. 输出重构后的数组。 

### 为什么它有效

 令实际队列为：```
p1, p2, p3, ..., pn
```对于每一个学生`pi`，记录为：```
(pi-1, pi+1)
```缺失的邻居被替换为`0`。 

当我们存储时：```
next[a] = b
```的记录`pi`贡献：```
next[pi-1] = pi+1
```因此：```
next[p1] = p3
next[p3] = p5
...
```这形成了奇数位置链。 

相似地：```
next[0] = p2
next[p2] = p4
...
```这形成了偶数位置链。 

第一个学生的唯一身份是前面的邻居`0`，所以我们知道`p1`。 遵循奇数位置链重建所有奇数位置，并遵循从`0`重建所有偶数位置。 交错这两条链会产生：```
p1, p2, p3, p4, ...
```这是原始队列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    nxt = {}
    first = None

    for _ in range(n):
        a, b = map(int, input().split())
        nxt[a] = b

        if a == 0:
            first = b

    ans = [0] * n

    cur = first
    idx = 0
    while cur != 0 and idx < n:
        ans[idx] = cur
        cur = nxt.get(cur, 0)
        idx += 2

    cur = nxt.get(0, 0)
    idx = 1
    while cur != 0 and idx < n:
        ans[idx] = cur
        cur = nxt.get(cur, 0)
        idx += 2

    print(*ans)

solve()
```字典`nxt`存储变换`next[a] = b`直接从输入记录导出。 

寻找`first`很容易。 每当我们遇到一对前邻居是`0`，第二个值是队列中第一个学生的 ID。 

第一个循环填充位置`0, 2, 4, ...`。 这些对应于队列位置`1, 3, 5, ...`在基于一的索引中。 下列的`nxt[cur]`从一个奇数位置移动到下一个奇数位置。 

第二个循环从`nxt[0]`，这是队列中的第二个学生。 遵循相同的映射遍历位置`2, 4, 6, ...`在基于一的索引中，将其写入数组索引`1, 3, 5, ...`。 

使用`dict.get(key, 0)`当链到达末端时避免关键错误。

 | 测量| 复杂性 | 说明|

 至多有`200000`同学们，线性时间很容易就足够快了。 内存使用率也很好`256 MB`限制。

 ## 边缘情况

 ### 长度为二的队列

 输入：```
2
0 20
10 0
```第一个学生是`10`。 奇数位链仅包含`10`，偶数位置链仅包含`20`。 

该算法产生：```
10 20
```无需特殊处理。 

### 学生人数为奇数

 输入：```
5
0 2
1 3
2 4
3 5
4 0
```奇数位置链为：```
1 -> 3 -> 5
```偶数位置链为：```
2 -> 4
```第一个链长了一个元素，每当队列长度为奇数时，就会出现这种情况。 交替写入恰好填充每个数组位置一次。 

### 非常大的学生证

 输入：```
3
0 900000
123456 0
900000 123456
```学生 ID 接近允许的最大值。 由于该实现使用哈希映射而不是索引数组，因此 ID 的大小对正确性或复杂性没有影响。 

重构后的队列为：```
900000 123456 0
```并且遍历逻辑保持不变。
