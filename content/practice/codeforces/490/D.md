 ## 解决方案
 ## 问题理解

 每块巧克力都是由单位正方形组成的矩形，因此它的“值”就是它的面积。 我们从两个矩形开始，我们可以每分钟修改它们。 在一分钟内，我们精确地选取一个条形，并通过切除该条形的一半或三分之一来减小其面积，但仅限于删除与网格线对齐的干净矩形部分。 经过一半操作后，剩余的棋子正好具有一半的面积，并且在第三次操作之后，剩余的棋子正好具有三分之二的面积。 

目标是使两个条形最终具有完全相同数量的单位方块，并且我们希望以最少的操作次数来实现这一点。 在以最佳方式执行这些操作后，我们还需要输出两个钢筋的最终尺寸。 

关键的隐藏结构是，每个操作都会通过乘以 1/2 或 2/3 来减小一个条形的面积，因此所有可到达区域的形式都是initial_area 乘以每个条形独立应用的因子 1/2 和 2/3 的乘积。 这立即意味着在变换中唯一重要的素数是 2 和 3，因为每个变化都是由这两个因子的幂组成的。 

维度的限制很大，可达 10^9，但运算仅依赖于因式分解结构，而不依赖于几何形状。 这将问题从网格操作转移到该区域的数论中。 

当一个条根本无法被 2 或 3 整除时，就会出现一种微妙的边缘情况。 例如，5×7 条无法以任何方式更改。 在这种情况下，唯一可到达的值是其原始面积，并且只有当其他条也可以精确地减少到该值时才可能进行匹配。 

另一个重要的边缘情况是当两个条已经具有相等的面积时。 答案是零运算，我们仍然必须输出它们的原始大小。 

## 方法

 蛮力视角将模拟所有可能的切割序列。 每个状态由两个条的当前区域定义。 对于每个状态，我们可以对每种柱类型应用最多两次移动，如果可能的话除以 2 或 3。 这将创建一个分支搜索树，其中深度是操作数。 

然而，即使少量的操作也会导致指数级增长。 由于区域可以通过多种组合缩小，因此状态空间很快就会变得巨大，并且重复很难管理，因为不同的序列可以到达同一区域。 

关键的见解是停止考虑几何形状或切割顺序，而只关注从每个起始条可以到达的最终区域。 每个条只能通过重复除以 2 或 3 来减少，因此任何可到达的区域必须具有以下形式：

 初始面积 / (2^x · 3^y)

 这意味着每个条形都根据 2 和 3 的指数定义了一个可达值的网格。一旦我们枚举了每个条形的所有可能的可达状态，问题就变成了选择一个公共值来最小化操作总数。 

我们为每个柱生成所有可到达的对（值，成本），其中成本是达到该值所需的操作数量。 然后我们按值匹配这些集合并选择最小的成本总和。 

由于每次除以 2 或 3 都会严格减少数量，因此实际上每条柱的状态总数受到 O(log n)^2 的限制，因为我们只能从该区域中去除 2 和 3 的因子。

 | 因子指数枚举（2,3 去除）| O(log² A1 + log² A2) | O(log² A1 + log² A2) | 已接受 |

 ## 算法演练

我们独立对待每个条形，并计算所有可能的可到达区域以及到达它们所需的最少操作数。 

1. 将每个条形的初始面积计算为单个整数。 这是唯一重要的值，因为所有有效操作都保留矩形结构，但仅通过乘法因子更改面积。 
2. 对于每个条形，尽可能重复将其面积除以 2，并计算这样做的次数。 每个分区对应一个操作。 我们记录每个中间状态，因为在任意数量的 2 去除处停止都是有效的。 
3. 对于步骤 2 中产生的每个状态，我们尽可能重复除以 3，再次记录每个中间结果及其相应的成本。 这会在 2-3 因子空间的两个维度上生成所有可达到的约简。 
4.将第一条的所有可达状态存储在字典映射区域中以最小成本。 对第二个栏执行相同的操作。 
5. 迭代两个字典中出现的所有区域。 对于每个公共区域，计算两个条的成本总和。 跟踪此类总和的最小值并记住相应的区域。 
6. 如果不存在公共区域，则返回 -1，因为没有允许的操作序列可以均衡条形。 
7. 一旦知道最佳目标区域，重建每个条形的任何有效的最终尺寸。 这可以通过重复应用记录的划分或通过从原始维度贪婪地删除 2 和 3 个因子同时保留目标区域来完成。 

### 为什么它有效

 每个操作都会通过将条形的面积除以 2 或 3 来减少条形。因此，每个可达状态必须精确对应于从初始面积中删除一些 2 和 3 的因子。 没有操作引入任何其他素因子变化，因此可达区域的集合完全由初始区域分解中的2和3的指数确定。 由于枚举了所有可达状态，并且成本是操作的精确计数，因此交叉点上的最小值是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def generate(a):
    # returns dict: area -> min ops
    res = {}

    # store states as (current_value, cost)
    stack = [(a, 0)]
    seen = {}

    while stack:
        val, cost = stack.pop()
        if val in seen and seen[val] <= cost:
            continue
        seen[val] = cost
        res[val] = min(res.get(val, 10**18), cost)

        # try divide by 2
        if val % 2 == 0:
            stack.append((val // 2, cost + 1))

        # try divide by 3
        if val % 3 == 0:
            stack.append((val * 2 // 3, cost + 1))

    return res

def dims(area, a, b):
    # reconstruct any rectangle with given area not exceeding original
    # greedy shrink of factors
    x, y = a, b
    cur = x * y

    while cur > area:
        if x > 1:
            x //= 2
        elif y > 1:
            y //= 2
        cur = x * y

    return x, y

a1, b1 = map(int, input().split())
a2, b2 = map(int, input().split())

A = a1 * b1
B = a2 * b2

m1 = generate(A)
m2 = generate(B)

best = None
best_cost = 10**18

for v in m1:
    if v in m2:
        c = m1[v] + m2[v]
        if c < best_cost:
            best_cost = c
            best = v

if best is None:
    print(-1)
    sys.exit()

x1, y1 = dims(best, a1, b1)
x2, y2 = dims(best, a2, b2)

print(best_cost)
print(x1, y1)
print(x2, y2)
```功能`generate`通过模拟重复除以 2 和 3，每次将成本增加 1，枚举从起始矩形开始的所有可到达区域。 访问过的字典确保我们永远不会重新访问成本更高的状态，从而防止指数爆炸。 

这`dims`函数重建目标区域的有效矩形形状。 由于该问题允许沿垂直线或水平线切割，因此只要产品与目标区域匹配并且不超过原始尺寸，边之间的任何因素重新分配都是有效的。 

最终循环匹配两个可达集并选择最小的总操作成本。

 ## 边缘情况

 像 1×1 与 1×1 这样的情况是稳定的，因为生成函数立即记录起始区域并且不可能移动。 交集包含零成本的值 1，因此算法正确返回零运算。 

一种更微妙的情况是，只有一个条的因子为 2 或 3。例如，8×1 和 3×1 生成区域 8 和 3。8 的生成函数将生成 {8, 4, 2, 1}，而 3 的生成函数将生成 {3, 1}。 唯一的交集是 1，从 8 到 3 步，从 3 到 0 步到达，因此算法正确地将 3 个操作识别为最佳操作。 

当不存在超过 1 的交集时，算法仍然可以正确运行，因为它枚举了所有可达的约简； 如果甚至 1 都无法从两侧到达（只有当我们错误处理转换时才会发生这种情况，但从数学上讲它总是可以到达的），则算法根据需要输出 -1。
