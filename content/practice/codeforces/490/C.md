 ## 解决方案
 ## 问题理解

 我们得到一个非常长的十进制数作为字符串。 它的长度可以达到一百万位，因此将其视为普通整数是不可能的。 

我们必须选择一个位置，将字符串切割成两个非空的部分。 左边的部分必须代表一个可被整除的正整数`a`。 右边的部分必须代表一个可被整除的正整数`b`。 两个部分都不能包含前导零。 由于原始数字本身没有前导零，因此只有正确的部分才可能违反此条件。 紧邻数字之前的剪切`'0'`无效。 

输出是任何有效的分割，或者`"NO"`如果不存在这样的分裂。 

约束完全决定了算法的方向。 字符串长度可以大到`10^6`， 尽管`a`和`b`至多是`10^8`。 任何重复将大子字符串转换为整数的解决方案都是没有希望的。 即使扫描整个字符串几次也已经接近实际极限。 我们需要一种算法，其运行时间与位数成线性关系。 

一些边缘情况值得关注。 

考虑：```
100
10 10
```分裂`10 | 0`满足整除条件，但右侧部分不是不带前导零的正整数。 正确答案是`"NO"`。 仅检查整除性是不够的。 

考虑：```
1050
1 50
```分裂`1 | 050`产生可被整除的右部分`50`，但它以零开头。 正确的分割是`10 | 50`。 

考虑：```
12
3 4
```唯一可能的削减是`1 | 2`。 左边的部分不能被整除`3`右边的部分不能被整除`4`，所以答案是`"NO"`。 该算法必须正确处理尽可能小的字符串长度。 

考虑：```
123456
1 6
```自从`a = 1`，每个前缀都可以被整除`a`。 粗心的实现可能会在第一个有效前缀处停止，而不检查右侧条件。 必须同时验证这两个条件。 

## 方法

 强力解决方案会尝试所有可能的切割位置。 对于每个位置，它将左子字符串和右子字符串转换为整数，检查整除性，并验证右子字符串不以`'0'`。 

这种方法在逻辑上是正确的，因为每个可能的分割都会被检查。 问题在于它的成本。 有`n - 1`可能的削减。 每次转换可能需要读取最多`O(n)`数字。 总工作量变为`O(n²)`。 和`n = 10^6`，这大约意味着`10^12`数字运算，远远超出极限。 

关键的观察是整除性仅取决于余数。 我们永远不需要实际的整数值。 

对于左边部分，我们可以从左到右扫描并保持余数模`a`：$$\text{rem} = (\text{rem} \cdot 10 + \text{digit}) \bmod a$$加工后位置`i`，我们知道前缀是否以`i`可以整除`a`。 

对于正确的部分，我们需要每个后缀模的余数`b`。 独立计算每个后缀又太昂贵了。 相反，从右向左扫描。 

假设我们从末尾开始处理数字。 如果当前数字对$10^k$后缀内的位置，其贡献模`b`是：$$\text{digit} \cdot 10^k \bmod b$$在向左移动的同时，我们保持当前十模的幂`b`。 这让我们可以在线性时间内计算每个后缀的余数。 

两次传球后，切入位置`i`在以下情况下有效：

 1. 前缀结尾为`i`可以整除`a`。 
2. 后缀开头为`i + 1`可以整除`b`。 
3. 后缀第一位数字不是`'0'`。 

我们只需扫描所有切割位置并输出第一个有效的位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取字符串`s`和整数`a`和`b`。 
2. 创建数组`pref`长度`n`。 
3. 从左到右扫描字符串。 

计算运行余数模`a`。 

储存于`pref[i]`是否有前缀`s[0..i]`可以整除`a`。 
4. 创建数组`suff`长度`n`。 
5. 从右向左扫描字符串。 

维护：

 - 当前后缀模的余数`b`- 当前十次幂的模`b`对于职位`i`：$$\text{rem} = (\text{digit} \cdot \text{power} + \text{rem}) \bmod b$$标记`suff[i]`如果此后缀余数等于零，则为真。 

更新：$$\text{power} = (\text{power} \cdot 10) \bmod b$$6. 检查每个切割位置`i`从`0`到`n - 2`。 
7.位置后的剪切`i`如果满足以下条件则有效：

 -`pref[i]`是真的。 
-`suff[i + 1]`是真的。 
-`s[i + 1] != '0'`。 
8. 一旦找到这样的位置，就打印`"YES"`、左子串和右子串。 
9. 如果不存在有效位置，则打印`"NO"`。 

### 为什么它有效

 在从左到右的传递过程中，保留的余数恰好是当前前缀模的值`a`。 这直接来自标准十进制扩展递归。 

在从右到左传递期间，保留的余数等于当前后缀模的值`b`。 每个数字都加上其正确的小数位值，以当前十模的幂表示`b`。 

因此，`pref[i]`当左边部分可以被整除时为真`a`， 和`suff[i+1]`当正确的部分能被整除时为真`b`。 额外检查`s[i+1] != '0'`相当于要求右侧部分没有前导零。 每一种可能的分割都会被测试一次，因此当且仅当存在一个有效的分割时，才会找到有效的分割。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    a, b = map(int, input().split())

    n = len(s)

    pref = [False] * n
    rem = 0

    for i in range(n):
        rem = (rem * 10 + int(s[i])) % a
        if rem == 0:
            pref[i] = True

    suff = [False] * n
    rem = 0
    power = 1

    for i in range(n - 1, -1, -1):
        digit = int(s[i])
        rem = (digit * power + rem) % b

        if rem == 0:
            suff[i] = True

        power = (power * 10) % b

    for i in range(n - 1):
        if pref[i] and suff[i + 1] and s[i + 1] != '0':
            print("YES")
            print(s[:i + 1])
            print(s[i + 1:])
            return

    print("NO")

if __name__ == "__main__":
    solve()
```第一遍计算前缀整除性信息。 十进制数的递归允许我们仅使用前一个余数和下一个数字来更新余数。 

第二遍计算后缀整除性信息。 我们不是重建每个后缀值，而是累加它的贡献模`b`。 变量`power`跟踪后缀内当前数字的位置值。 

最后的循环检查每个合法的剪切。 上限是`n - 2`因为两个部分都必须非空。 条件`s[i + 1] != '0'`很容易被忽视。 如果没有它，字符串如`"1050"`会错误地接受分割`"1 | 050"`。 

没有整数大于`a`或者`b`被存储，因此即使字符串包含一百万位，该算法也能工作。

 ## 边缘情况

 考虑：```
100
10 10
```唯一具有潜在吸引力的分割是：```
10 | 0
```前缀可以被整除`10`并且后缀可以被整除`10`，但后缀以`'0'`。 在最终扫描期间，算法检查`s[i + 1] != '0'`，拒绝切割，并输出：```
NO
```考虑：```
1050
1 50
```存在两种可整除有效割断：```
1 | 050
10 | 50
```第一个被拒绝，因为后缀以零开头。 第二个通过了所有检查并被返回。 这证实了仅可除性是不够的。 

考虑：```
12
3 4
```只有一处切口：```
1 | 2
```前缀余数取模`3`是`1`，后缀余数取模`4`是`2`。 这两个条件都不成立。 扫描结束时没有找到有效的剪切，产生：```
NO
```考虑：```
123456
1 6
```每个前缀都可以被整除`1`，因此前缀条件始终为真。 该算法在接受任何切割之前仍然会验证后缀的整除性和前导零规则。 这可以防止过早接受并表明两半都是独立对待的。
