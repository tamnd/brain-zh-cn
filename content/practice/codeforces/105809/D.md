 ## 解决方案
 ## 问题理解

 我们有两种代币。 

第一种由标签组成`1, 2, ..., m`。 这些标记中的每一个都是唯一的，因此标签在单个排列中最多可以出现一次。 

第二种由`n`标签副本`0`。 这些副本是无法区分的，因此安排只关心值在哪里`0`出现，而不是使用哪个物理零令牌。 

排列是一个有序序列，其长度`L`可以是任意值`1`到`n`。 

对于每个有效长度，我们必须计算在每个非零标签最多使用一次的规则下可以形成多少个不同的序列。 答案需要模数`10^9 + 7`。 

这些约束足够小，足以建议组合计数解决方案。 两个都`m`和`n`至多是`1000`，所以一个`O(nm)`算法执行大约一百万次迭代，这已经足够快了。 任何强力生成排列都是不可能的，因为有效序列的数量呈指数增长。 

一些边缘情况很容易处理不当。 

认为`m = 1`和`n = 1`。```
Input
1 1
```有效的安排是`[0]`和`[1]`，所以答案是`2`。 

仅计算包含非零标记的排列的解决方案将错误地返回`1`。 

考虑：```
Input
2 2
```长度`2`包含诸如以下的安排`[0,0]`,`[0,1]`,`[1,0]`,`[1,2]`， 和`[2,1]`。 安排`[1,1]`是非法的，因为令牌`1`是唯一的，不能重复使用。 将非零标签视为可重复使用的计数公式会过度计数。 

另一个重要的情况是当所需的长度超过唯一标签的数量时。```
m = 2, L = 5
```最多可以出现两个非零标签。 任何允许的公式`k > m`不同的非零标记将计算不可能的排列。 

## 方法

 最直接的想法是生成每个允许长度的每个排列并将其插入到集合中。 这是正确的，因为每个有效序列都被显式构造并计数一次。 

问题是，即使对于中等值，排列的数量也会变得巨大。 搜索空间随着长度呈指数增长，使得暴力破解完全不可行。 

我们可以对它们进行计数，而不是生成序列。 

固定长度`L`。 让`k`是排列中使用的非零标记的数量。 

自从有了标签`1..m`是独一无二的，确切地说`k`必须选择不同的标签，并且每个选择的标签出现一次。 

首先选择哪个`k`之间的位置`L`位置将包含非零标签。 这有助于$$\binom{L}{k}$$方式。 

现在填写那些`k`具有不同标签的位置`1..m`。 

我们需要一个有序的选择`k`不同的标签，即$$P(m,k)=m(m-1)\cdots(m-k+1)$$方式。 

乘以独立选择给出$$\binom{L}{k} P(m,k).$$对每个有效值求和`k`计算所有长度的排列`L`。$$\text{count}(L)
=
\sum_{k=0}^{\min(L,m)}
\binom{L}{k} P(m,k).$$最后，对所有允许的长度求和：$$\text{answer}
=
\sum_{L=1}^{n}
\sum_{k=0}^{\min(L,m)}
\binom{L}{k} P(m,k).$$自从`m,n ≤ 1000`，我们可以计算这个双和`O(nm)`使用预先计算的阶乘和逆阶乘计算时间。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 最佳| O(纳米) | O(m+n) | 已接受 |

 ## 算法演练

 1. 阅读`m`和`n`。 
2. 预先计算阶乘高达`max(m,n)`模数`10^9 + 7`。 
3. 使用费马定理预先计算逆阶乘。 
4. 对于每个长度`L`从`1`到`n`, 迭代`k`从`0`到`min(L,m)`。 
5. 计算$$\binom{L}{k}
=
\frac{L!}{k!(L-k)!}$$使用阶乘和逆阶乘。 
6. 计算$$P(m,k)
=
\frac{m!}{(m-k)!}.$$7. 添加$$\binom{L}{k}P(m,k)$$对答案取模`10^9 + 7`。 
8. 打印最终金额。 

### 为什么它有效

 每种长度的安排`L`包含一些数字`k`非零标签。 

一次`k`是固定的，排列由两个决定唯一确定：哪些位置包含非零标签，以及哪些不同标签的有序集合占据这些位置。 

因素`C(L,k)`计算位置选择。 因素`P(m,k)`计算不同标签的有序分配。 每个有效的排列恰好对应于一对这样的选择，并且每个这样的选择都会产生一个有效的排列。 

总结所有有效的`k`值对每个排列只计数一次。 对所有长度求和可以计算问题中的每个有效排列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

m, n = map(int, input().split())

mx = max(m, n)

fact = [1] * (mx + 1)
for i in range(1, mx + 1):
    fact[i] = fact[i - 1] * i % MOD

inv_fact = [1] * (mx + 1)
inv_fact[mx] = pow(fact[mx], MOD - 2, MOD)

for i in range(mx, 0, -1):
    inv_fact[i - 1] = inv_fact[i] * i % MOD

def comb(a, b):
    if b < 0 or b > a:
        return 0
    return fact[a] * inv_fact[b] % MOD * inv_fact[a - b] % MOD

ans = 0
fact_m = fact[m]

for L in range(1, n + 1):
    limit = min(L, m)
    for k in range(limit + 1):
        perm = fact_m * inv_fact[m - k] % MOD
        ans = (ans + comb(L, k) * perm) % MOD

print(ans)
```阶乘和反阶乘数组允许在恒定时间内计算每个组合值。 

排列计数$$P(m,k)=\frac{m!}{(m-k)!}$$也是在恒定时间内从同一个表中获得的。 

嵌套循环迭代每个有效对`(L,k)`。 自从`L`永远不会超过`1000`，迭代总数约为 100 万次，完全在限制范围内。 

一个常见的错误是忘记案例`k = 0`。 该术语表示完全由零组成的排列，例如`[0]`或者`[0,0,0]`。 这些安排是有效的并且必须被计算在内。 

另一个常见的错误是允许`k > m`。 只有`m`可用的不同非零标签，因此这种状态是不可能的。

 ## 边缘情况

 考虑：```
1 1
```为了`L = 1`，算法评估`k = 0`和`k = 1`。`k = 0`作出安排`[0]`。`k = 1`作出安排`[1]`。 

答案就变成了`2`，这是正确的。 任何启动的实施`k`从`1`会想念`[0]`。 

考虑：```
2 2
```为了`L = 2`，算法只允许`k = 0, 1, 2`。 

什么时候`k = 2`，贡献是$$C(2,2)\cdot P(2,2)=1\cdot2.$$这些正是`[1,2]`和`[2,1]`。 

无效序列`[1,1]`和`[2,2]`从未出现，因为`P(2,2)`计算不同标签的有序选择。 

考虑：```
2 5
```尽管长度是五，但循环限制$$k \le \min(L,m)=2.$$该算法从不尝试使用三个不同的非零标签，因为只存在两个。 这正确地强制执行了唯一性约束。
