 ## 解决方案
 ## 问题理解

 我们得到一个长度的数组`n`和一个极限`k`。 我们希望将数组分成尽可能少的连续段。 在每个段内，不同值的数量不得超过`k`。 

任务不是计算所有有效分区。 我们只需要覆盖整个数组所需的最小数量的段，同时遵守不同值的限制。 

这些限制非常具有启发性。 数组长度可以达到`10^5`，因此任何检查所有子数组或在所有间隔上执行动态规划的算法都过于昂贵。 一个`O(n²)`解决方案需要大约`10^10`在最坏的情况下进行操作，这是完全不可行的。 我们需要接近线性时间的东西。 

另一个有用的观察来自值范围。 每个数组元素满足`1 ≤ a[i] ≤ 1000`， 和`k ≤ 1000`。 由于值很小，因此维持滑动窗口内元素的频率非常便宜。 

一个常见的错误是认为平衡段长度可能会有所帮助。 目标只是尽量减少段的数量。 段大小本身是无关紧要的。 

考虑数组：```
3 1
1 2 3
```每个段最多可以包含一个不同的值。 唯一有效的分区是：```
[1] [2] [3]
```答案是：```
3
```另一个容易被忽略的情况是：```
5 2
1 2 1 2 3
```一旦该段已经包含，粗心的策略可能会被削减`k`独特的价值观。 这会产生：```
[1 2 1 2] [3]
```这实际上是最佳的并给出了答案`2`。 

重要的细节是一个段可能恰好包含`k`独特的价值观。 仅当添加下一个元素会增加计数时，我们才需要进行剪切`k`。 

第三种边缘情况是所有值都相同时：```
3 1
1 1 1
```整个数组已经满足条件，所以答案是：```
1
```任何在遇到重复边界时盲目创建新段的实现都会在这里失败。 

## 方法

 最直接的暴力想法是从左到右构建段，对于每个起始位置，尝试所有可能的结束位置，同时计算不同的值。 一旦选择了一个段，就对剩余的后缀进行递归。 

这是有效的，因为每个有效的分区都可以被探索。 问题是间隔的数量。 有`O(n²)`子数组，甚至有效地检查不同的计数也不能挽救整体的复杂性。 和`n = 10^5`，这样的做法是没有希望的。 

关键的观察是我们只需要最小数量的段，并且每个段都受到最大数量的不同值的约束。 

假设我们当前正在构建一个段。 只要添加下一个元素即可保持最多不同值的数量`k`，延长段永远不会有坏处。 延长一个段只会为后面的段留下更少的元素。 由于我们的目标是最小化段的数量，因此我们应该始终尽可能地扩展当前段。 

这立即表明了一种贪婪的策略。 开始一个segment，不断添加元素，直到segment最多包含`k`不同的值，并且下一个元素将创建的时刻`(k+1)`-th 不同值，关闭当前段并从该元素开始一个新段。 

为什么这种贪婪的选择是最优的？ 任何有效的分区必须不晚于当前段的结束点`(k+1)`出现第-个不同值。 我们的贪婪段是最长的有效段。 用这个最长的有效段替换任何较短的第一个段不能增加以后需要的段的数量。 对剩余后缀重复相同的参数证明了最优性。 

因为价值观最多是`1000`，我们可以在恒定时间内维护每个元素的频率和当前不同值的数量。 每个元素只被处理一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最优贪心计数不同值 | O(n) | O(1000) | 已接受 |

 ## 算法演练

 1. 创建值的频率数组`1..1000`。 
2. 从一个段和一个空频率结构开始。 
3. 从左到右遍历数组。 
4. 对于当前值`x`，检查当前段中是否已经存在。 
5.如果`x`是新的并且当前段已经完全包含`k`不同的值，然后添加`x`会违反约束。 开始一个新的段。 

重置所有频率，将不同计数器重置为零，并将答案加一。 
6. 插入`x`通过更新其频率进入当前段。 
7. 如果这是第一次出现`x`在当前段中，增加不同的计数器。 
8.处理完所有元素后，输出段数。 

### 为什么它有效

 在任何时候，算法维护的当前段都是以当前位置结束的最长有效段。 每当一个新的不同值使计数超过`k`，每个有效分区都被迫在该值之前结束当前段。 贪心选择尽可能延迟切割，产生最大的可行片段。 较大的第一段永远不会比较小的第一段需要更多的段来用于剩余后缀。 重复应用此参数会生成具有尽可能少的段数的分区。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

freq = [0] * 1001
distinct = 0
ans = 1

for x in a:
    if freq[x] == 0 and distinct == k:
        ans += 1
        freq = [0] * 1001
        distinct = 0

    if freq[x] == 0:
        distinct += 1
    freq[x] += 1

print(ans)
```其实现完全遵循贪婪策略。 

变量`distinct`存储当前存在于活动段中的不同值的数量。 频率数组让我们可以在恒定时间内确定某个值是否第一次出现在该段内。 

微妙的部分是操作的顺序。 我们必须首先检查添加当前值是否会超出不同值限制。 只有在决定是否需要新段后，我们才插入该值。 

当新段开始时，当前元素属于该新段。 这就是插入逻辑在重置后运行的原因。 

值范围的边界为`1000`，因此重置频率阵列只需花费`O(1000)`时间。 因为至多`n`段可以存在并且`1000`是一个常数，总体复杂度保持线性。

 ## 边缘情况

 考虑：```
3 1
1 2 3
```该算法从段计数开始`1`。 读完后`1`，该段具有一个独特的值。 阅读`2`将创造第二个独特的价值，同时`k = 1`，因此新的段开始。 同样的情况也发生在`3`。 最终的答案是`3`，这是最佳的，因为每个段可能只包含一个不同的值。 

现在考虑：```
5 2
1 2 1 2 3
```处理前四个元素后，该段恰好包含两个不同的值，`{1,2}`。 什么时候`3`出现，添加它会创建第三个不同的值。 该算法开始一个新的段并放置`3`那里。 答案就变成了`2`。 任何具有一个段的分区都是无效的，因为整个数组包含三个不同的值。 

最后：```
3 1
1 1 1
```不同计数永远不会超过 1。 不需要任何切割，算法输出`1`。 这证实重复出现已存在的值不会影响不同值限制。
