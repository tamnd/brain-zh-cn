 ## 解决方案
 ## 问题理解

 我们给出了三个整数，我们可以将它们视为数轴上的点：$a_1$,$a_2$， 和$a_3$。 目标是使数字处于中间$a_2$尽可能接近其他两个的算术平均值，使用以下操作任意多次：选择两个不同的数字，将其增加一个$1$，并将另一个递减$1$。 “算术平均偏差”衡量的是$a_2$来自完美算术平均值：它是$a_1 + a_3 - 2a_2$。 

输入由多个测试用例组成，每个测试用例给出一个三元组数字。 对于每个测试用例，输出是我们使用允许的操作可以实现的最小算术平均偏差。 

查看约束条件，数字最多可达$10^8$，并且最多可以有$5000$测试用例。 这排除了任何尝试按顺序模拟所有可能操作的方法，因为所需的移动次数可能约为$10^8$，这在一秒钟之内远远超出了可行的范围。 相反，我们需要一个直接用于算术推理的解决方案。 

当总和时，会出现不明显的边缘情况$a_1 + a_3$要么就在上面，要么就在下面$2a_2$，特别是当差异为奇数时。 在这种情况下，即使我们可以通过增量和减量来移动数字，偏差也无法达到零，因为我们只能按整个单位进行调整。 例如，$(2, 2, 6)$只能达到偏差$1$因为完美的意思$4$将需要非整数移动。 

## 方法

 蛮力方法将尝试每一种可能的递增/递减操作，直到偏差停止减小。 对于三元组的数字，每次操作都会发生变化$a_1 + a_3 - 2a_2$经过$\pm 2$,$\pm 0$，或类似的组合。 这种方法是正确的，因为最终偏差将达到可实现的最小值。 然而，模拟所有这些操作是不可行的，因为我们可能需要$10^8$每个测试用例的操作，导致$5\times 10^{11}$最坏情况下的操作。 

关键的观察是该操作保留了总和$a_1 + a_2 + a_3$。 它也相当于在保持整数差的同时移动数字。 从数学上讲，可实现的最小偏差就是以下情况下的余数：$a_1 + a_3 - 2a_2$除以$2$，取绝对值。 这是因为每个操作都会改变表达式$a_1 + a_3 - 2a_2$正是通过$2$，让我们能够将其带到$0$如果是偶数，或者$1$如果是奇数。 

换句话说，问题归结为计算$|a_1 + a_3 - 2a_2| \bmod 2$。 如果初始偏差是均匀的，我们可以达到零。 如果是奇数，我们只能达到一个。 这个简单的算术推理允许$O(1)$每个测试用例的解决方案。

 | 最佳 | 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量$t$。 我们将独立处理每个测试用例。 
2. 对于每个测试用例，读取三个数字$a_1$,$a_2$,$a_3$。 
3. 计算当前算术平均偏差：$dev = a_1 + a_3 - 2 \cdot a_2$。 这给出了中间数的两倍与极值之和之间的有符号差。 
4. 可实现的最小偏差是绝对值$dev \bmod 2$，可以计算为`abs(dev % 2)`。 如果初始偏差是偶数，我们可以得到$0$。 如果是奇数，则最小偏差为 $1`。 
5. 打印此测试用例的最小偏差。 

为什么它有效：每个操作都会修改$a_1 + a_3 - 2a_2$增量为$2$，无论是正数还是负数。 因此，偏差的奇偶性是模不变的$2$，这决定了我们能否达到零。 这个不变量保证了正确性，并且足以计算最小偏差而无需模拟操作。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a1, a2, a3 = map(int, input().split())
    dev = a1 + a3 - 2 * a2
    print(abs(dev) % 2)
```该代码首先读取测试用例的数量，然后迭代每个三元组。 我们直接计算偏差，然后取其绝对值模 2。使用快速 I/O 可以避免不必要的开销。 模运算确保我们正确处理正偏差和负偏差，并且`abs`保证非负输出。 不需要对负数或大值进行特殊处理，因为 Python 可以安全地处理整数算术。

 偏差为 -6，偶数，因此最小偏差为 0。
