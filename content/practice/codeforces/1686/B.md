 ## 解决方案
 ## 问题理解

 我们得到了以下数字的排列`1`到`n`。 我们可以将这个排列分成任意数量的连续部分。 每一块都是一个子数组。 

对于每个子数组，我们查看其反转计数。 如果子数组的反转计数为奇数，则该子数组称为奇数。 我们的目标是选择分裂方式，使得奇数子数组的数量尽可能多。 

每个测试用例的输出是奇数子数组的最大可能数量。 

这些限制立即表明我们需要一个非常轻量级的解决方案。 总和为`n`所有测试用例最多`2 · 10^5`，这意味着`O(n)`或者`O(n log n)`解决方案很容易足够快。 任何重复计算子数组的反转计数的方法都是不可能的，因为即使是单个反转计算也可能需要`O(n log n)`时间。 

有几种容易被忽略的情况。 

考虑一个已经排序的排列：```
1 2 3 4
```每个子数组都有零个反转，这是偶数。 正确答案是`0`。 盲目创建许多段的贪婪策略将会失败，因为创建更多段不会自动创建奇数反转奇偶校验。 

考虑：```
2 1
```整个数组只有一个反转。 正确答案是`1`。 分裂成`[2]`和`[1]`给出两个偶数子数组并丢失唯一的奇数段。 

考虑：```
4 3 2 1
```答案是`2`，通过实现`[4,3]`和`[2,1]`。 只检查整个排列的奇偶校验的粗心方法会忽略分裂会增加奇数段的数量。 

关键的困难在于我们要最大化奇数段的数量，而不是整个数组的总反转奇偶校验。 

## 方法

 蛮力方法会尝试排列的每一种可能的分割。 有`2^(n-1)`方法在相邻元素之间放置切口，所以这已经是无望的了。 即使我们以某种方式生成了所有分割，我们仍然需要计算每个结果子数组的反转奇偶校验。 

暴力破解在概念上是正确的原因很简单：检查每个有效分区，因此最终找到最佳答案。 问题是巨大的搜索空间。 

为了找到更好的解决方案，我们需要了解子数组奇数的原因。 

一个非常有用的观察来自于查看长度为 2 的子数组。 

如果两个相邻元素形成递减对，```
p[i] > p[i+1]
```然后子数组`[p[i], p[i+1]]`恰好包含一个反转，因此很奇怪。 

这立即为我们提供了有保证的奇数段。 

现在假设我们遇到这样一个递减的相邻对。 是否有任何理由将任一元素与相邻位置保持在一起？ 

不。 

如果我们将这两个元素分离为一段，我们立即获得一个奇数子数组。 包含它们的任何较大段最多贡献一个奇数子数组，因为无论每个段包含多少个反转，都只计算一次。 

因此，每当我们看到相邻对递减时，我们应该将这两个元素作为自己的段并计算一个答案。 

使用职位后`i`和`i+1`，两个位置都不能参与另一个段。 我们跳过两者并继续。 

这变成了一个简单的贪心过程。 

为什么它是最优的？ 因为每个奇数段必须包含至少一个反转。 在排列中，每个反转链都包含一些相邻的递减对。 每当我们找到这样的一对时，立即将其作为长度为2的奇数段，使用尽可能少的元素数来获得一个奇数子数组。 没有其他分区可以从这两个位置提取超过一个奇数段。 

整个问题归结为计算我们可以贪婪地采取多少个不相交的相邻反转。

 ## 算法演练

 1. 初始化答案`0`。 
2. 使用索引开始从左到右扫描排列`i`。 
3.如果`p[i] > p[i+1]`，则该对形成一个长度为 2 的子数组，并且只有一个反转。 
4. 将这一对计为一个奇数子数组，并将答案增加`1`。 
5. 通过移动跳过两个位置`i`转发通过`2`。 

我们这样做是因为这两个元素已经被提交到一个最佳奇数段，并且重用任一元素都不能增加总计数。 
6. 否则，移动`i`转发通过`1`。 

仅从该相邻对中无法获得奇数段。 
7. 继续，直到剩余元素少于两个。 
8. 输出答案。 

### 为什么它有效

 每当段内存在反转时，该段内的某处必定至少存在一个相邻的递减对。 因此，计数为奇数的段必须包含至少一个相邻反转。 

当我们遇到相邻的反转时`p[i] > p[i+1]`，仅由这些位置组成的二元素段已经是奇数了。 恰好使用两个元素来获得一个奇数段是最佳的，因为没有任何分区可以从这两个相同的位置获得多个奇数子数组。 

选择这样的一对后，任何最优解都可以转化为在不减少奇数段数量的情况下隔离该对的最优解。 因此，从左到右贪婪地获取每个可用的相邻反转永远不会损害未来的选择。 

所选择的对是不相交的，并且每一对恰好贡献一个奇数子阵列。 因此贪心计数是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        res = 0
        i = 0

        while i < n - 1:
            if p[i] > p[i + 1]:
                res += 1
                i += 2
            else:
                i += 1

        ans.append(str(res))

    sys.stdout.write("\n".join(ans))

solve()
```该算法维护一个指针`i`扫描一次排列。 

每当`p[i] > p[i+1]`，我们发现了一个相邻的反演。 该对本身形成一个奇数子数组，因此我们对其进行计数并跳过两个位置。 

跳过是微妙的部分。 如果我们只向前移动一个位置，重叠的对可能会被计数多次。 单个元素不能属于分区中的两个不同段，因此重叠选择无效。 

当该对增加时，那里不存在长度为二的奇数段，因此我们只需前进一个位置即可。 

由于每个索引最多被访问一次，因此运行时间是线性的。

 ## 边缘情况

 考虑最小可能的排列：```
1
1
```扫描永远不会进入循环，因为没有相邻对。 答案依然存在`0`，这是正确的，因为每个长度为 1 的子数组都有零个反转。 

考虑：```
1
3
3 2 1
```扫描看到`(3,2)`并计算一个奇数段。 然后跳到最后。 答案是`1`。 

一个常见的错误是同时计算两者`(3,2)`和`(2,1)`，生产`2`。 这需要位置`2`属于两个不同的部分，这是不可能的。 

考虑完全递增的排列：```
1
5
1 2 3 4 5
```不存在相邻反转。 该算法永远不会增加答案并返回`0`。 每个子数组都有偶数反转计数，因此这是正确的。 

考虑：```
1
4
4 3 2 1
```算法算数`(4,3)`和`(2,1)`单独并返回`2`。 这些对是不相交的，因此两者可以同时成为奇数段。 这说明了为什么在选择一对后跳过两个位置是正确的行为。
