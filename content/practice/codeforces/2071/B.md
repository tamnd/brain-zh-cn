 ## 解决方案
 ## 问题理解

 我们被要求构造一个从 1 到 n 的数字排列，使得排列的前缀和不是完全平方。 输入提供了多个测试用例，每个测试用例指定一个整数 n。 对于每个 n，我们要么输出满足条件的排列，如果不可能则输出 -1。 

挑战来自于置换和与完美平方之间的相互作用。 一种简单的方法会尝试所有排列并检查前缀和，但 n 最多可以达到 500,000，并且所有测试用例的 n 总和可以达到 1,000,000。 任何 O(n²) 算法都会立即被排除，因为以简单的方式检查所有排列甚至所有前缀和将超出实际限制。 

第一个边缘情况是n = 1。唯一的排列是[1]，前缀和是1，是完全平方，所以输出必须是-1。 其他较小的 n 值需要小心处理，因为较小的序列更容易意外生成完全平方和。 

当 n 本身是完全平方数或对从 1 到 n 的数字进行顺序求和时产生的前缀和是完全平方数时，会出现第二种不明显的边缘情况。 简单地按顺序打印 1 到 n 的粗心方法会失败，因为像 1、3、6、10、15… 这样的前缀和包含 1 和 4，它们是完全平方数。 

## 方法

 暴力方法生成所有排列并检查它们的前缀和。 原则上这是可行的，因为我们可以通过对前缀求和并与完美平方进行比较来验证正确性。 然而，排列的数量随 n 呈阶乘增长，因此即使 n = 10 也远远超出了实际计算的范围。 

关键的见解是完全平方和是稀疏的，通过反转或仔细打乱片段，我们可以确保没有前缀和达到完美平方。 一种实用的方法是在连续的完美正方形之间进行块操作。 如果我们在每个块内反向处理数字，我们可以保证下一个数字相加不会达到下一个完全平方数。 这一观察结果将问题简化为构造性算法：将序列划分为长度与连续完美平方之间的差异相对应的块，然后反转每个块。 

这将每个测试用例的时间复杂度降低到 O(n)，因为我们只迭代 n 个元素一次来分配位置。 存储排列的内存使用量也是 O(n)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!·n) | O(n!·n) | O(n) | 太慢了|
 | 建设性块| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 使用简单的循环预先计算直到 n 的所有完美平方。 我们需要这些来了解块边界。 
2. 初始化一个空的排列数组。 
3. 将当前指针设置为 1。对于每个完全平方 s，将块大小计算为 s - 当前 + 1。 
4. 按从 s 向下到 current 的相反顺序插入数字来填充该块。 这确保了前缀和永远不会碰到 s 本身。 
5. 将 current 更新为 s + 1 并重复，直到放置完所有数字。 
6. 打印结果排列。 

为什么有效：根据构造，任何前缀和都不能等于完全平方，因为每个块中最后一个数字的位置使得总和超过完全平方。 反转块可确保最后一个数字之前的总和永远不会到达平方。 这个不变量适用于所有块，并且它们一起覆盖从 1 到 n 的整个序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    import math
    t = int(input())
    for _ in range(t):
        n = int(input())
        if n == 1:
            print(-1)
            continue
        
        perm = []
        current = 1
        while current <= n:
            sq = int(math.ceil(math.sqrt(current))) ** 2
            end = min(sq, n)
            block = list(range(current, end + 1))
            perm.extend(block[::-1])
            current = end + 1
        
        print(' '.join(map(str, perm)))

if __name__ == "__main__":
    solve()
```该解决方案使用`math.ceil(math.sqrt(current))`找到下一个完美的正方形。 每个块都被反转并附加到排列中。 使用`min(sq, n)`确保我们不超过 n。 像 n = 1 这样的边缘情况会被显式处理。

 ## 边缘情况

 显式处理最小输入 n = 1。 对于 n = 1，任何排列都无法避免前缀和等于 1，因此输出为 -1。 

对于刚好低于完全平方的 n，例如 n = 8，块分解可确保反转连续平方之间的数字块，以防止任何前缀和成为平方。 例如，1 到 4 形成一个块，5 到 8 形成另一块。 通过反转，我们可以避免像 1、4、9 这样的和。每一步都保留了前缀和不能达到完美平方的不变量。
