 ## 解决方案
 ## 问题理解

 我们有一棵树，一个起始顶点`st`，和一个目标顶点`en`。 

必须选择所有顶点的排列。 期间`i`第步，一块奶酪出现在顶点`p[i]`。 如果鼠标已经在那里，它就会留下来。 否则，它只会沿着唯一的简单路径向该顶点移动一条边。 

排列决定了景点的顺序。 我们必须对所有顶点进行一次排序，以便在处理整个排列后，鼠标最终到达顶点`en`。 

任务不是模拟固定的过程。 我们可以自由选择排列本身。 

该树最多包含`10^5`所有测试用例的顶点。 由于顶点总数的边界为`10^5`， 一个`O(n log n)`或者`O(n)`每个测试用例的解决方案很容易足够快。 任何涉及测试许多排列的事情都是不可能的。 即使检查只有 15 个顶点的树的所有排列也已经需要超过一万亿种可能性。 

该问题最危险的部分是鼠标每一步仅移动一个边缘。 一个幼稚的策略可能会试图让老鼠沿着一条完整的路径走向`en`，但稍后放置奶酪可以再次将其拉开。 

考虑一个简单的链：```
1 - 2 - 3
st = 2
en = 2
```如果我们选择排列`[1,2,3]`，鼠标移动```
2 -> 1 -> 2 -> 3
```并结束于`3`，不在`2`。 

另一个微妙的情况是当鼠标经过`en`在最后一步之前。```
1 - 2 - 3 - 4
st = 1
en = 4
```排列`[4,1,2,3]`使鼠标到达`4`立即，但后来的景点把它拉走了。 达到`en`早还不够。 只有最终的位置才重要。 

正确的解决方案必须保证最终位置，无论处理最后一个顶点时鼠标当前在哪里。 

## 方法

 强力解决方案将生成顶点的每个排列并模拟鼠标。 对于长度的排列`n`，模拟需要`O(n)`步骤。 有`n!`排列，所以总复杂度是`O(n·n!)`。 

即使是为了`n = 15`，这是完全不可行的。 

关键的观察来自于相对于陷阱顶点查看树`en`。 

树根位于`en`。 现在每个顶点的深度等于其距`en`。 

假设我们按深度递减的顺序处理顶点。 直观上，我们首先在树的最深处展示奶酪，然后才在根部附近展示奶酪。 

为什么这有用？ 

采取任何步骤，奶酪出现在某个顶点`v`。 如果鼠标尚不存在，它会将一侧边缘移向`v`。 

当顶点从较大深度到较小深度处理时，每个未处理顶点的深度不大于当前顶点。 在有根树中，向更深的顶点移动不能使鼠标远离已处理的更深的顶点集。 该过程逐渐向根部塌陷。 

关键的事实是这个排序中的最后一个顶点是`en`本身，因为它是具有深度的唯一顶点`0`。 

当我们处理最终顶点时，鼠标始终位于树中的某个位置。 奶酪出现在`en`，鼠标向`en`。 排序的结构保证了在消耗了所有先前的顶点之后，鼠标的位置与包含的剩余活动子树一致`en`，迫使最终位置为`en`。 

更正式的查看它的方式是通过势函数。 让`d(v)`表示深度从`en`。 以递减的深度处理顶点可确保处理完所有深度大于的顶点后`k`，鼠标最多必须位于由深度顶点诱导的子树内部`k`。 这个不变量缩小直到只有`en`遗迹。 

为了构建排列，我们只需要每个顶点的深度`en`。 按深度递减对顶点进行排序立即给出有效的答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |

 |---|------|---|

 | 蛮力 | O(n·n！) | O(n) | 太慢了|

 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 以顶点为树根`en`。 
2. 从以下位置开始运行 DFS 或 BFS`en`并计算每个顶点的深度。 
3. 创建一个包含所有顶点的列表。 
4. 按深度递减对顶点进行排序。 
5. 输出结果顺序作为排列。 

按深度递减排序的原因是距离陷阱较远的顶点首先被处理。 靠近陷阱的顶点会延迟到最后。 

1. 自从`en`有深度`0`，它成为排列的最后一个元素。 

### 为什么它有效

 树根位于`en`。 

对于一个顶点`x`，将其深度定义为其距离`en`。 

考虑排列中尚未出现的顶点集。 因为我们从最大到最小处理深度，所以这个集合总是连接的并且包含`en`。 

最初，所有顶点均未处理。 

当一个顶点`v`被处理后，它是最深的剩余顶点之一。 任何朝着`v`无法强制鼠标移出由剩余顶点形成的连接区域。 移除后`v`从考虑来看，鼠标仍然位于剩余的连接组件内，其中包含`en`。 

在每个步骤后重复此参数表明，在处理完除最后一个顶点之外的所有顶点后，鼠标必须位于剩余的集合内。 唯一剩下的顶点是`en`，所以鼠标必须位于`en`当该过程结束时。 

因此，产生的排列总是能把老鼠困在陷阱里。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, st, en = map(int, input().split())

        g = [[] for _ in range(n + 1)]

        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        parent = [-1] * (n + 1)
        depth = [0] * (n + 1)

        stack = [en]
        parent[en] = 0

        while stack:
            u = stack.pop()

            for v in g[u]:
                if v == parent[u]:
                    continue

                parent[v] = u
                depth[v] = depth[u] + 1
                stack.append(v)

        order = list(range(1, n + 1))
        order.sort(key=lambda x: depth[x], reverse=True)

        print(*order)

solve()
```DFS 计算距离`en`，成为有根树的深处。 

父数组防止将边遍历回父数组。 由于图是一棵树，因此足以访问每个顶点一次。 

知道深度后，唯一剩下的任务就是排序。 距离较远的顶点`en`出现在排列中的较早位置。 因为`en`有深度`0`，它自然就成为最后一个元素。 

无需特殊处理`st`。 施工适用于每个起始位置。 

一个容易犯的错误是把树扎根于`st`而不是`en`。 正确性参数完全取决于距陷阱顶点的距离。 使用任何其他根都会破坏证明。 

另一个常见的错误是按深度递增的顺序排序。 那个地方`en`第一个而不是最后一个并且通常会失败。

 ## 边缘情况

 ### 具有单个顶点的树

 输入：```
1
1 1 1
```DFS 分配深度`0`到顶点`1`。 

排序的顺序很简单：```
[1]
```老鼠在陷阱处开始和结束。 

### 陷阱等于起始顶点

 输入：```
1
3 2 2
1 2
2 3
```深度为：```
1 -> 1
3 -> 1
2 -> 0
```排列结束于`2`。 

即使老鼠从陷阱开始，较早出现的奶酪也可能会将其移开。 最终亮相于`2`保证进程正确完成。 

### 陷阱是一片叶子

 输入：```
1
4 1 4
1 2
2 3
3 4
```深度从`4`：```
1 -> 3
2 -> 2
3 -> 1
4 -> 0
```排列变为：```
[1, 2, 3, 4]
```陷阱仍然最后出现。 证明仅取决于深度`en`，而不是树的形状。 

### 同一深度的多个顶点

 输入：```
1
5 1 3
3 1
3 2
3 4
3 5
```所有的叶子都有深度`1`。 

这些叶子之间的任何排序都是有效的，因为正确性证明只需要不增加的深度。 等深度的顶点可以以任何顺序出现。
