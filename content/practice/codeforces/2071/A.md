 ## 解决方案
 ## 问题理解

 三名玩家重复进行比赛，其中只有两名球员在场，一名球员在观看。 角色分配使用两条规则从之前的匹配中确定性地演变。 如果有人已经连续打了两场比赛，他们将被迫下一场比赛。 否则，获胜者和前一位观众将成为下一场比赛的选手，而失败者将成为观众。 

我们没有被要求模拟玩家的身份。 唯一重要的是特定球员的位置：第一场比赛的观众。 对于每个查询索引 k，我们必须确定在游戏的任何有效演化下，该同一玩家是否也可以成为第 k 场比赛的观众。 

约束允许 k 最大为 10^9，因此任何显式模拟逐步匹配的方法都是立即不可行的。 线性模拟每个测试用例需要多达十亿次转换，即使对于 1000 个查询，这也远远超出了时间限制。 

重要的隐藏结构是，尽管比赛结果引入了分支（因为获胜者可能会有所不同），但观众角色的演变受到“不能连续三场比赛”规则引起的严格周期性约束。 这迫使系统进入第一场比赛观众的短周期。 

边缘情况主要是关于较小的 k 值。 对于 k = 1，答案显然是肯定的。 当 k = 2 时，第一场比赛的观众不能保持观众身份，因为必须有两名选手上场，因此观众被迫立即上场。 任何忽略这种强制参与的推理都会在 k = 2 时立即失效。 

## 方法

 暴力方法将模拟所有可能的比赛状态，同时跟踪原始观众是否仍然可以担任该角色。 每个状态取决于最后两到三场比赛的配置以及观众的身份。 由于获胜者并不固定，因此这会成为一个分支过程，并且比赛数量可能会呈指数级爆炸。 

即使我们简化并仅跟踪单个确定性序列，我们仍然需要为每个查询计算最多 k 个转换。 当 k 达到 10^9 时，这是不可能的。 

关键的观察是我们不需要对所有玩家进行完整的身份跟踪。 我们只需要知道在至少一次有效的进化中，单个指定玩家是否可以在时间 k 时担任旁观者角色。 这将问题简化为分析由最近的参与模式确定的非常小的状态空间中的可达性。 

禁止任何球员连续参加三场比赛的规则迫使球员定期轮换角色。 在展开前几次转换后，系统稳定为周期 3 的观众参与重复模式。对有效序列的直接检查表明，第 1 场比赛的观众只能作为观众重新出现在与 1 模 3 一致的位置。 

这将问题从模拟转换为模块化算术。

 ## 算法演练

1. 观察前几场比赛并仅跟踪第一场比赛观众的观众角色。 我们不会追踪完整的玩家身份，只会追踪该玩家是否仍然是观众或被迫参加比赛。 
2. 从第 1 场比赛到第 2 场比赛，观众必须参与，因为每场比赛只有一名球员闲置，角色限制迫使人员流动。 这消除了 k = 2 作为有效观众位置的情况。 
3. 继续推理更多步骤。 因为任何参加两次比赛的球员都必须在接下来的比赛中退出，所以系统会强制进行严格的轮换，每个球员最多只能连续参加两次比赛，然后强制休息。 
4. 一旦这个模式扩展了足够的步骤，我们就会观察到一个重复的结构，其中观众角色每 3 场比赛循环一次。 
5. 得出结论，第一场比赛的观众恰好出现在比赛 k 处，其中 k == 1 (mod 3)。 

工作原理：由于“不能连续进行三场比赛”规则，与观众身份相关的系统状态完全由长度为 2 的有界历史决定。 这导致了一个只有几个可到达状态的有限自动机。 单个演化角色序列上的任何有限自动机最终都必须变成周期性的，直接枚举显示周期为 3，初始对齐为索引 1。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    k = int(input())
    if k % 3 == 1:
        print("YES")
    else:
        print("NO")
```该实现直接应用周期性结果。 每个测试用例都是独立的，并且只需要一次模运算。 

唯一微妙的一点是对齐。 第一场比赛的索引为 k = 1，在这个位置，观众基本上是同一个玩家，因此正确的同余类是 1 模 3，而不是 0 模 3。 

## 工作示例

 考虑样本输入。 

对于 k = 1, 2, 333, 1e9，我们对 k 求模 3。 

| k | k 模 3 | 结果 |
 | --- | --- | --- |
 | 1 | 1 | 是 |
 | 2 | 2 | 否 |
 | 333 | 333 0 | 否 |
 | 1000000000 | 1 | 是 |

 第一个案例证实了基本条件。 第二种情况显示了第一场比赛后的强制休息。 第三和第四种情况展示了大指数的周期性结构，其中只有模块化位置很重要。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        k = int(input())
        out.append("YES" if k % 3 == 1 else "NO")
    return "\n".join(out)

# provided samples
assert run("4\n1\n2\n333\n1000000000\n") == "YES\nNO\nNO\nYES"

# minimum case
assert run("1\n1\n") == "YES"

# second position always fails
assert run("1\n2\n") == "NO"

# periodic checks
assert run("3\n3\n4\n5\n") == "NO\nYES\nNO"

 ## 边缘情况

 对于 k = 1，观察者与初始观察者基本上是相同的，因此输出为“是”，没有应用任何转换。 模规则正确地得出 1 mod 3 = 1。 

当 k = 2 时，系统会强制前一个观众积极参与游戏，因此答案一定是否定的。 规则 k % 3 = 2 立即证实了这一点。 

对于 k = 3，即使可以进行多次演化，但观众角色已经远离原来的观众，因此答案仍然是否定的。 模条件 k % 3 = 0 正确地排除了它。 

对于 k = 4，循环重置对齐，使系统回到原来的观众可以重新出现为观众的状态，匹配 k % 3 = 1。
