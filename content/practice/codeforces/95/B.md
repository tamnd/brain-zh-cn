 ## 解决方案
 ## 问题理解

 我们需要构造最小的数，至少是`n`并且同时满足两个条件。 每个数字必须是`4`或者`7`，以及总数`4`s 必须等于总计数`7`s。 

输入是一个十进制字符串，可以非常长，最多可达`10^5`数字。 这立即改变了问题的性质。 我们不能将值视为普通的整数类型，也不能逐一向上迭代检查每个数字。 当长度变大时，即使生成相同大小的所有幸运数字也是不可能的，因为有`2^L`可能的幸运字符串长度`L`。 

目标数字的结构给出了更强的限制。 有效答案的长度必须为偶数，因为`4`沙`7`s 必须完全匹配。 对于一个长度`2k`， 确切地`k`职位包含`4`另一个`k`包含`7`。 

困难的部分是不生成有效的数字。 困难的部分是生成至少仍然是的最小有效数字`n`。 

一些边缘案例打破了天真的贪婪想法。 

假设输入是：```
5000
```粗心的从左到右的贪婪策略可能会从`7`因为`4`会使前缀太小。 放置后`7`，它可能会尝试最小化其余部分并产生`7447`。 但正确答案是：```
7474
```因为`7447 < 5000`。 

当不存在具有相同长度的有效数字时，会出现另一种微妙的情况。```
7777
```长度没有超级幸运数`4`那至少是`7777`，因为最大的是`7744`。 正确答案成为下一个偶数长度的最小有效数：```
444777
```奇数长度也需要小心。```
100
```超级幸运数字不能有长度`3`，所以答案必须跳至长度`4`:```
4477
```最后一个棘手的情况发生在回溯期间。 考虑：```
4748
```贪婪的构造可能会匹配`474`然后在最后一位数字处失败，因为只有`4`和`7`是允许的。 该算法必须回溯到较早的位置并小心地增加它。 正确答案是：```
4774
```如果没有回溯逻辑，构造就会陷入困境。 

## 方法

 蛮力的想法很简单。 开始于`n`，一一递增，测试当前数字是否超级幸运。 检查本身很简单：扫描数字，验证每个数字是`4`或者`7`，并计算每个出现的数量。 

这适用于微小的输入，但搜索空间会立即爆炸。 周围长度`10`，数字已经达到数十亿。 输入甚至可以包含`10^5`数字，所以直接数字迭代是完全不可能的。 

一种稍微好一点的暴力方法是生成所需长度的所有超级幸运数字，并选择至少是最小的一个`n`。 对于一个长度`2k`，我们选择哪个`k`职位包含`4`，给予：$$\binom{2k}{k}$$候选人。 

对于长度`20`，这已经是关于`184756`。 对于长度`100`，它变得天文数字般大。 这些限制完全排除了这一点。 

关键的观察是我们只需要字典顺序上最小的有效字符串大于或等于`n`。 这将问题转化为受限数字构造问题。 

我们在跟踪时从左到右构建答案：

 1. 多少`4`留下来。 
2. 多少`7`留下来。 
3、构造的前缀是否已经严格大于对应的前缀`n`。 

如果前缀已经较大，则应通过放置尽可能多的数字来贪婪地最小化剩余数字`4`尽可能先。 

如果前缀仍然相等，则每个选择都必须遵守由`n`。 

这自然就变成了带有剪枝的深度优先搜索。 在每个位置我们尝试放置`4`首先因为我们想要最小的答案。 如果该选择不可能导致有效完成，我们会尝试`7`。 

搜索仍然高效，因为每个位置只有两个可能的数字，并且修剪会立即删除几乎所有无效分支。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数/不可行 | O(1) | O(1) | 太慢了|
 | 最佳| 最坏情况 | O(L²) O(L) | 已接受 |

 这里`L`是答案中的位数。 

## 算法演练

 1. 将输入读取为字符串而不是整数。 

输入最多可以包含`10^5`数字，因此固定大小的数字类型无法存储它。 
2. 如果长度为`n`是奇数，立即将目标长度增加到下一个偶数。 

超级幸运号码必须包含相同数量的`4`沙`7`s，所以它的长度总是偶数。 
3. 尝试用当前长度构造一个答案。 

如果当前长度大于原始长度，则最小可能的有效数字就是：```
444...777...
```两个数字的计数相等。 
4. 否则，对位置运行递归 DFS。 

DFS状态包含：

 - 当前指数
 - 剩余数量`4`- 剩余数量`7`- 当前前缀是否已经大于`n`5. 在每个位置尝试数字`4`第一的。 

我们更喜欢`4`因为我们想要字典顺序最小的有效答案。 
6. 立即跳过无效的选择。 

如果我们已经使用了太多`4`或`7`s，该分支无法工作。 

如果前缀仍然相等并且所选数字小于中对应的数字`n`，该分支也无法工作。 
7. 输入数字后，更新`greater`旗帜。 

一旦构造的前缀变得严格大于前缀`n`，其余数字只需满足平衡条件即可。 
8. 如果递归调用到达末尾且两个计数都为零，则返回构造的字符串。 
9. 如果当前长度不存在解，则将长度增加`2`并返回该长度的最小有效数。 

### 为什么它有效

 该算法在整个构造过程中保持一个简单的不变量：

 当前前缀总是可以扩展到至少一个有效的超级幸运数字，且不小于`n`。 

每当我们放置一个数字时，我们都会立即拒绝违反此不变量的选择。 尝试`4`前`7`保证字典最小性，因为第一个成功的分支是最小可能的完成。 

如果当前长度的每个分支都失败，则不存在该长度的有效数字。 最小的有效数字必须具有下一个偶数长度，并且在所有这些数字中，最小排列是所有`4`s 后面跟着所有`7`s。 

## Python 解决方案```python
import sys
from functools import lru_cache

input = sys.stdin.readline

def solve():
    n = input().strip()
    m = len(n)

    if m % 2 == 1:
        m += 1
        print('4' * (m // 2) + '7' * (m // 2))
        return

    while True:
        half = m // 2

        if m > len(n):
            print('4' * half + '7' * half)
            return

        @lru_cache(None)
        def dfs(pos, fours, sevens, greater):
            if pos == m:
                return "" if fours == 0 and sevens == 0 else None

            limit = n[pos]

            for d in ['4', '7']:
                if d == '4':
                    if fours == 0:
                        continue
                else:
                    if sevens == 0:
                        continue

                if not greater and d < limit:
                    continue

                ngreater = greater or (d > limit)

                res = dfs(
                    pos + 1,
                    fours - (d == '4'),
                    sevens - (d == '7'),
                    ngreater
                )

                if res is not None:
                    return d + res

            return None

        ans = dfs(0, half, half, False)

        if ans is not None:
            print(ans)
            return

        m += 2

if __name__ == "__main__":
    solve()
```解决方案从处理最简单的不可能的情况开始。 如果输入长度是奇数，则没有有效答案可以具有相同的长度，因此我们立即移动到下一个偶数长度并直接构造最小平衡幸运数。 

递归函数是算法的核心。 它的参数完整地描述了剩余的搜索空间。 这`greater`旗帜尤其重要。 虽然它是`False`，每个数字选择必须保持数字至少与相应的前缀一样大`n`。 Once it becomes`True`，下界限制消失。 

记忆可以防止重复探索相同的状态。 如果没有缓存，不同的路径可能会重新访问相同的路径`(position, remaining fours, remaining sevens, greater)`配置多次。 

尝试数字的顺序很重要。 我们总是测试`4`前`7`。 Since DFS returns immediately after finding a valid completion, this guarantees the final answer is lexicographically smallest.

 One subtle implementation detail is comparing digits as characters. 自从`'4' < '7'`按字典顺序匹配数字顺序，直接字符比较工作正常。 

另一个微妙之处是当不存在相同长度的解决方案时的回退。 我们将长度增加`2`，不是由`1`，因为有效长度必须保持偶数。 

## 工作示例

 ### 示例 1

 输入：```
4500
```| 职位| 当前前缀 | 剩余 4s | 剩余 7s | 大于 n 前缀 |
 | --- | --- | --- | --- | --- |
 | 0 | 4 | 1 | 2 | 假|
 | 1 | 47 | 47 1 | 1 | 真实|
 | 2 | 474 | 474 0 | 1 | 真实|
 | 3 | 4747 | 0 | 0 | 真实|

 该算法排名第一`4`因为匹配第一个数字可以保持可能性。 在第二个位置，放置`4`会产生前缀`44`，它已经小于`45`，所以它选择`7`。 从那时起，前缀已经更大，因此剩余的数字被贪婪地最小化。 

### 示例 2

 输入：```
7777
```| 尝试长度| 结果 |
 | --- | --- |
 | 4 | 不存在有效号码 |
 | 6 | 最小的有效数字是`444777`|

 对于长度`4`，每个有效数字恰好包含两个`4`和两个`7`是。 最大的这个数字是`7744`，它仍然小于`7777`。 DFS 穷尽所有可能性并失败。 然后算法直接跳转到length`6`。 

这个例子说明了为什么增加长度有时是不可避免的。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(L²) | 记忆 DFS 访问大多数 O(L²) 状态 |
 | 空间| O(L²) | 缓存存储 DFS 状态 |

 状态数量受以下限制：$$L \times \frac{L}{2} \times \frac{L}{2} \times 2$$这简化为`O(L²)`因为计数`4`沙`7`s 链接在一起。 

和`L ≤ 10^5`，实际搜索空间仍然是可管理的，因为 DFS 会积极修剪并且只探索可行的前缀。 该解决方案完全符合限制。

 ## 边缘情况

 考虑输入：```
100
```长度为`3`，这很奇怪。 该算法立即知道有效答案不能有长度`3`，因为相等的计数`4`和`7`要求长度均匀。 它将长度增加到`4`并构造最小平衡数：```
4477
```现在考虑：```
7777
```DFS 尝试所有长度平衡的幸运数`4`。 每个有效候选人最多`7744`，所以所有分支都会失败。 然后算法将长度增加到`6`和输出：```
444777
```这表明某一长度的失败并不意味着整体施工失败。 

最后，检查：```
4748
```该算法首先尝试贪婪地匹配前缀：

 -`4`-`47`-`474`在最后一位数字上，两者都没有`4`也不`7`可以在保留下限的同时完成有效答案。 递归回溯到前一个位置并将第三个数字替换为`7`，生产：```
4774
```这证实了当局部最小选择阻止稍后所有有效完成时，DFS 正确地修改了早期决策。
