 ## 解决方案
 ## 问题理解

 我们被要求选择一个数字$x$2 和 之间$n$包含在内，使得所有倍数的总和$x$不超过$n$被最大化。 例如，如果$n = 15$我们选择$x = 2$，倍数为 2, 4, 6, 8, 10, 12, 14，它们的和为 56。我们保证有一个唯一的最优$x$对于每个$n$。 输入由多个测试用例组成，每个测试用例指定一个值$n$，输出是一个整数$x$每个测试用例。 

约束条件$2 \le n \le 100$很小，这意味着任何近似于二次的解$n$是可以接受的，但我们仍然应该寻求一种更简单的基于观察的方法。 唯一性保证让我们确信我们的方法总是会产生一个正确的答案。 

当发生微妙的边缘情况时$n$是素数还是小数。 例如，如果$n = 3$，候选人是$x = 2$和$x = 3$。 2 的倍数得到 2，3 的倍数得到 3，所以正确答案是 3。总是选择最小的一个简单的方法$x$或者依赖于可分性模式可能会在这里失败。 

另一个边缘情况是当$n$是均匀的。 经常，$x = 2$主导总和，因为它产生许多倍数，并且较高的值会快速减少项数。 认识到这种模式对于最佳方法至关重要。 

## 方法

 蛮力方法很简单：对于每个候选人$x$从 2 到$n$，我们计算的倍数之和$x$不超过$n$。 倍数之和可以直接计算为$x + 2x + 3x + \dots + kx$在哪里$k = \lfloor n / x \rfloor$。 这可以使用算术级数公式有效地计算$x \cdot k \cdot (k+1) / 2$。 对于每个$n$，我们测试所有$x$并跟踪金额最大的那个。 和$n \le 100$，每个测试用例最多涉及 100 个候选者，这对于 100 个测试用例来说已经足够快了，但仍然值得寻找更简单的见解。 

关键的观察是给定的总和$x$可以重写为$x \cdot k \cdot (k+1) / 2$， 在哪里$k = n // x$。 该函数随着两个相互竞争的因素而增长：$x$本身，数字越大，它就越大，并且$k$，倍数的数量，减少为$x$增加。 什么时候$x$很小，$k$很大，产生很多项，但是$x$很小。 什么时候$x$很大，$k$规模小，产品有限。 测试小$n$表明$x = 2$或者$x = n$通常是唯一要检查的候选人。 系统分析证实最大总和发生在$x = 2$或在$x = n$。 因此，最佳方法是仅计算这两个候选者的总和并选择较大的一个。

 ## 算法演练

 1.读取测试用例数量$t$。 每个测试用例都是独立的，因此我们可以循环处理它们。 
2. 对于每个测试用例，读取整数$n$。 
3. 计算倍数之和$x = 2$。 让$k_2 = n // 2$，那么总和就是$2 \cdot k_2 \cdot (k_2 + 1) // 2$。 
4. 计算倍数之和$x = n$。 这里，$k_n = n // n = 1$，所以总和是$n$。 
5. 比较两个总和。 如果总和为$x = 2$越大，输出2； 否则，输出$n$。 
6. 对所有测试用例重复此操作。 

为什么它有效：倍数函数的总和具有以下形式$x \cdot k \cdot (k+1)/2$以及相互竞争的影响$x$和$k$取极端，2 和$n$，唯一要考虑的候选人。 测试表明没有其他$x$在该范围内可以产生更大的总和，保证正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    sum2 = 2 * (n // 2) * ((n // 2) + 1) // 2
    sumn = n
    if sum2 > sumn:
        print(2)
    else:
        print(n)
```该代码读取测试用例的数量并在每个测试用例上循环$n$。 它计算的倍数之和$x = 2$和$x = n$，使用整数除法和算术级数公式来避免循环。 比较处理最佳选择$x$。 一个微妙的实现选择是确保使用整数除法来获得$k = n // x$，否则算术级数将不正确。

 ## 边缘情况

 对于$n = 2$，唯一的候选者是 2。该算法计算 sum2 = 2 且 sumn = 2。由于 sum2 不大于 sumn，因此输出 2。对于$n = 3$，2 和 3 都是候选数，并且算法正确地选择 3，因为 3 的总和超过 2 的总和。对于像这样的素数$n = 97$, 总和为$x = 2$是 2_48_49/2 = 2352，97 的总和是 97。算法输出 2，这与小值的观察结果一致$x$通常占主导地位，除非$n$本身就是最大的贡献者。 这证实了该方法可以处理所有微妙的情况。
