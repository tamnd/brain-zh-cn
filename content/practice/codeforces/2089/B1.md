 ## 解决方案
 ## 问题理解

 我们有两个长度相等的数组。 您可以将每个索引视为一个包含两堆单元的站：一堆来自数组`a`和数组中的一堆`b`。 该过程以同步轮次运行，并且每个轮次都有固定的结构。 

每一轮、每个位置`i`首先删除之间尽可能多的匹配单元`a[i]`和`b[i]`，有效地消除局部重叠。 取消后，无论剩余内容`a`以循环方式向右移动一步，这种移动的配置成为新的配置`a`为下一轮。 这`b`阵列在所有回合中都保持在原位。 

目标是确定需要多少轮才能达到所有值`a`到处都变为零。 自从`k = 0`，我们不允许预处理或修改`a`在该过程开始之前。 

约束很严格：所有测试用例最多有 2×10^5 个元素，并且值可以大到 10^9。 这立即排除了任何逐轮处理元素的模拟，因为在最坏的情况下，轮数和每轮的总工作量都会使其远远超出可行的限制。 

简单的模拟会重复地重新计算整轮，移动数组和匹配值，导致复杂度约为 O(n × 答案)，这个复杂度太大了，因为在病理情况下答案本身可能大到 O(n) 或更糟。 

当移位导致残差时，会出现微妙的边缘情况`a`质量反复循环而不被立即吸收`b`。 例如，如果`b`非常小，除了在一个位置，剩余的`a`在完全耗尽之前，质量将绕轨道运行多次。 任何贪婪的每步本地消耗而不跟踪全局流延迟都会低估轮数。 

## 方法

 关键的困难在于，每一轮都包含两个相互作用的影响：`a`经过`b`，以及剩余部分的循环移位。 如果我们扩展这个过程，每个单元`a[i]`每轮有效地向右“行进”一步，并且在它访问的每个位置，它都可以被可用容量吸收`b`。 

强力模拟将显式维护数组并重复应用舍入规则。 每轮的成本为 O(n)，在最坏的情况下，在所有值消失之前我们可能需要 O(n) 轮，每个测试用例的总时间为 O(n²)。 当 n 达到 2×10^5 时，这是不可能的。 

关键的观察是停止循环思考，而是考虑每个位置随着时间的推移可以吸收多少总“容量”。 各指标`i`有固定容量`b[i]`每轮只能使用一次，但由于移动，每个元素`a`最终以可预测的循环顺序经过多个位置。 这将问题转化为确定沿每个循环路径的累积可用容量何时足以满足所有资源贡献的需求。`a`。 

一旦重新构建，我们可以将这个过程解释为一个循环累积问题。 每个位置都贡献一个沿着周期移动的供应，而每个节点都有固定的每轮接收能力。 所有供应单元都已匹配的最早时间对应于在双阵列结构上的滑动前缀和意义上所有需求第一次得到满足的时间。 

我们将问题简化为跟踪，对于每个起始位置，在遍历循环时其传出质量被完全吸收需要多长时间。 这可以使用前缀和以及对重复数组的二进制提升或双指针样式扫描来计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n²) | O(n) | 太慢了 |
 | 前缀+循环扫描（最优）| O(n log n) 或 O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 通过考虑以 n 为模的索引，将数组逻辑加倍，以便循环运动变成长度为 2n 的概念数组上的线性运动。 这消除了环绕复杂性并允许区间推理。 
2. 计算表示剩余不匹配需求的前缀结构`a`当它传播时。 各单位在`a[i]`必须被分配到某个职位`j ≥ i`(mod n) 其中容量存在于`b[j]`。 
3、将每个仓位换算成“供给减去产能”的余额值`d[i] = a[i] - b[i]`。 正值代表必须沿着周期推进的过剩需求。 
4. 在双倍数组上构建这些余额的前缀累积。 目标是找到所有前缀赤字永远不会超过零的最小分段长度，这意味着所有需求都在该轮次窗口内得到满足。 
5. 使用两指针扫描：扩展右边界，同时保持产能减去需求的运行剩余。 如果盈余变为负数，则将左边界向前移动，直到恢复可行性。 
6. 所有起始位置所需的最大窗口长度对应于所需的最小轮数，因为每一轮都会将所有剩余需求向前移动一步。 
7. 输出这个最大窗口长度作为测试用例的答案。 

### 为什么它有效

 取消和转移的过程相当于沿着固定周期移动需求单位，同时以固定容量消耗它们。 每个单元的`a`每轮确定性地移动一步，因此它的整个行为是通过双周期的线性遍历来捕获的。 贪婪窗口维护确保在每个前缀处，我们分配的需求永远不会超过可用容量，这正是最终完全吸收的条件。 由于每个单元都遵循相同的循环路径，因此最慢满足的单元决定了总轮数，这是由最大可行段长度捕获的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    # net surplus at each position
    d = [a[i] - b[i] for i in range(n)]
    
    # double array for circular handling
    d = d * 2
    
    left = 0
    cur = 0
    ans = 0
    
    for right in range(2 * n):
        cur += d[right]
        
        while cur > 0:
            cur -= d[left]
            left += 1
        
        if right - left + 1 >= n:
            ans = max(ans, right - left + 1)
    
    print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```实现的核心思想是将动态取消压缩成一个平衡数组`d`。 我们不是模拟运动，而是根据盈余和赤字进行推理。 两指针窗口强制要求在任何有效段内，容量永远不会满足需求。 将数组加倍允许将每个循环间隔表示为连续的段。 

变量`cur`跟踪当前窗口中剩余的未匹配需求量。 当它变得无效时，左边界被推进以恢复可行性。 

答案是跨越至少一个完整周期长度的最大窗口`n`，因为完成一个完整的循环对应于完成一轮完整的换档行为。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个索引最多进入和离开滑动窗口一次 |
 | 空间| O(n) | 我们存储一个双倍数组用于循环推理 |

 线性复杂度至关重要，因为总输入大小达到 2×10^5，任何二次行为都会立即超出限制。 滑动窗口确保每个位置的摊销恒定工作量。

 ## 边缘情况

 一个棘手的情况是当所有`a[i] <= b[i]`。 在这种情况下，每个位置在第一轮中都是可以本地取消的，因此答案应该是 1。算法处理这个问题是因为`d[i]`始终为非正数，因此滑动窗口永远不会违反约束并立即形成全周期有效段。 

另一种情况是单个集中质量`a`反对遥远的能力`b`。 质量块有效地围绕循环旋转，直到到达吸收位置。 双数组窗口自然地捕获了这个完整的遍历，并且最大段长度扩展到完整的循环长度，产生等于的正确轮数`n`。
