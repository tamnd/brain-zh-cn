 ## 解决方案
 ## 问题理解

 给定一个无向连通图，其中每条边都有一个正整数权重。 从这个图中我们必须选择一个生成树，这意味着我们准确地选择$n-1$保持所有顶点连接且不包含环的边。 在所有可能的生成树中，我们计算一个分数，定义为所有选定边缘权重的按位或，并且我们希望这样的分数尽可能最小。 

因此，我们不是像经典 MST 问题那样最小化总权重，而是最小化所选边之间的按位或运算。 这改变了优化的本质：添加边缘永远不会“取消”信息，它只会在最终结果中设置更多位。 

限制很严格，但并不极端。 所有测试用例的顶点和边的总数最多为$2 \cdot 10^5$，这意味着任何解决方案在边总数上都应大致呈线性或接近线性。 任何像在边缘上尝试所有生成树或位掩码 DP 之类的事情都是立即不可能的，因为生成树的数量在密集图中呈指数增长。 

一个天真的想法是尝试使用 Kruskal 或 Prim 构建最小生成树，但这会优化总和，而不是按位或，并且无法控制位传播。 另一个天真的想法是尝试形成生成树的所有边子集，但即使对于中等图，这也是天文数字。 

当图形有多种替代方式使用仅高位不同的边连接组件时，就会出现微妙的边缘情况。 例如，如果一条边的权重为 1（二进制`001`），另一个权重为 2（二进制`010`），选择其中一个可能在局部看起来不错，但 OR 的累积方式不同，具体取决于连接强制哪些边。 

粗心的贪婪策略（例如按权重对边进行排序并挑选较小的边）可能会失败，因为稍大的边可以避免在其他地方引入高位，从而减少最终的 OR。 

真正的困难在于 OR 运算是全局且单调的，因此我们需要考虑被迫包含哪些位。 

## 方法

 暴力的观点是想象选择一棵生成树并计算它的 OR 值。 生成树的数量呈指数级增长，因此这是不可行的。 甚至枚举可以形成树的所有边子集也是如此$O(2^m)$，验证每个子集的连接性是另一个$O(n)$，使其完全无法使用。 

关键的观察是倒转视角。 我们可以问：我们可以避免哪些位，而不是直接尝试最小化“或”？ 

如果我们确定一个候选答案$X$，那么我们问是否存在仅使用其权重不引入禁止位的边的生成树，即所有边必须满足$w \& \sim X = 0$。 换句话说，我们选择的每条边都必须是子掩码$X$，否则会引入一点外部$X$。 

所以对于一个固定的$X$，我们可以通过构建一个仅由允许的边组成的子图并验证其是否连通来检查可行性。 如果它是连通的，那么生成树完全存在于这个子图中，并且该树的 OR 最多自动$X$，因为每条边仅贡献内部位$X$。 

这将问题转化为寻找最小的位掩码$X$使得由包含在中的边形成的图$X$已连接。 自从$X$最多有 30 位，我们可以从最高位向下贪婪地构建它：如果在不使用包含它的边的情况下仍然可以实现连接，我们会尝试保持未设置的位。 

为了测试是否可以删除某个位，我们暂时将边缘限制为不包含该位的边缘，并使用 DSU 检查连接性。 如果连接性被保留，我们就将该位清零； 否则我们必须将其包括在内。 

这会从最高位（大约$10^9$) 降至 0。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（所有树）| 指数| O(n) | 太慢了 |
 | 位掩码 + DSU 每位可行性 |$O(30 \cdot m \cdot \alpha(n))$|$O(n)$| 已接受 |

 ## 算法演练

 我们独立解决每个测试用例。 

1. 我们将答案掩码初始化为所有位设置，通常$(1 << 30) - 1$。 这代表我们可能被迫进入的最大可能的 OR 值。 
2. 我们处理从最高相关位到 0 的位。每个位代表是否允许包含设置了该位的边。 
3. 对于固定位$b$，我们尝试在答案中将其关闭。 我们暂时假设最终的 OR 中不需要该位。 
4. 为了测试这个假设，我们只考虑权重不包含位的边$b$如果我们试图禁止它。 这模拟了我们完全禁止这一点的想法。 
5. 我们在这些过滤的边上运行 DSU，并检查所有顶点是否都已连接。 如果它们是连接的，则可以在不使用任何具有位的边的情况下构建生成树$b$，所以我们从答案中永久清除这一位。 
6. 如果连接失败，我们将恢复答案中的位，这意味着需要具有该位的某些边来连接图。 
7. 处理完所有位后，得到的掩码是最小可能的 OR。 

正确性取决于这样一个事实：删除一点对应于删除所有引入它的边缘。 如果图在该限制下保持连接，那么我们可以安全地在任何生成树中完全避免该位。 

保持的不变量是，在从高到低处理位之后，由于连接限制，所有会产生较小 OR 掩码的配置都已被证明是不可行的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

def solve():
    t = int(input())
    for _ in range(t):
        input()  # empty line

        n, m = map(int, input().split())
        edges = []
        for _ in range(m):
            u, v, w = map(int, input().split())
            edges.append((u - 1, v - 1, w))

        ans = (1 << 30) - 1

        for b in range(29, -1, -1):
            dsu = DSU(n)
            for u, v, w in edges:
                if (w & ans) == 0 or (w & (1 << b)) == 0:
                    dsu.union(u, v)

            if len({dsu.find(i) for i in range(n)}) == 1:
                ans ^= (1 << b)

        print(ans)

if __name__ == "__main__":
    solve()
```DSU 是按大小并集的标准路径压缩，仅用于连接检查。 主要的微妙之处在于在每个位测试期间如何过滤边缘：我们只允许与当前候选掩码一致的边缘，并且我们显式测试删除一个位是否仍然允许完全连接。 

检查连接性的线路使用一组 DSU 根。 这比跟踪组件数量的效率稍低，但在给定的限制下仍然可以接受。

 ## 边缘情况

 一种重要的边缘情况是多个边缘提供替代连接但仅位结构不同。 例如，如果一条路径使用低权重边，但在删除一位时断开连接，而另一条路径使用较高权重边，但保留连接性，则算法会正确检测到删除该位的不可行性，因为 DSU 连接在限制下失败。 

另一种情况是当图已经是一棵树时。 在这种情况下，每条边都是必要的，并且算法将永远无法删除任何边权重中出现的位，因为删除它们会立即断开图的连接。 

最后，当所有边缘共享一个公共高位时，该位就变得不可避免。 DSU 检查将在顶层对该位进行失败，将其锁定为最终答案，然后在该约束下独立优化较低的位。
