 ## 解决方案
 ## 问题理解

 我们在序列中得到三个固定位置：第一个值`a`, 第二个值`b`，和第三个值`c`。 我们只允许进行一次修改操作：选择这三个位置之一并将其乘以某个正整数`m`我们的选择。 

在这个单一的改变之后，我们希望得到的三元组按照给定的顺序形成算术级数。 这意味着中间元素必须恰好位于第一个和第三个元素的中间，或者等效于条件`2 * middle = first + third`必须持有。 

任务不是明确地构造级数，而只是确定是否存在这样的指数和乘数选择。 

测试用例的数量限制很严格，最多 10⁴，但每个测试用例都是持续的工作。 这立即排除了任何涉及搜索值的事情`m`或列举候选人。 自从`m`可以大到 10⁸，任何超过可能乘数的暴力破解都是不可能的。 

这个问题的微妙部分是修改一个值会不对称地改变结构。 一种幼稚的方法可能会尝试所有索引选择和所有可能的选择`m`，但这引入了巨大的搜索空间。 

通常破坏错误解决方案的边缘情况来自对称性和零差异情况。 例如，当所有数字都相等时，如果我们选择，任何一个元素的乘法仍然允许 AP`m = 1`。 另一个棘手的情况是当 AP 已经成立时：我们仍然被迫应用一个运算，但乘以 1 可以保留它。 粗心的解决方案可能会忘记“什么都不做”是允许的`m = 1`。 

第二个重要的角点是当 AP“几乎有效”但需要调整必须满足严格线性关系而不仅仅是差值相等的中间元素时。 

## 方法

 暴力方法会尝试每个索引`i ∈ {a, b, c}`以及每一个可能的乘数`m`，重新计算三元组，并检查它是否构成算术级数。 这在原则上是正确的，因为它探索了所有允许的操作。 

然而，这立即失败了，因为`m`范围可达 10⁸。 即使我们限制自己以代数方式检查可行性，迭代值也是不可能的。 真正的问题不仅仅是尺寸`m`，但如何不存在单调结构`m`影响不同索引选择的 AP 条件。 

关键的观察是我们不需要搜索`m`根本不。 相反，我们可以假设哪个位置被修改并直接求解`m`使用算术级数条件。 

如果我们固定索引，AP 条件就变成了一个线性方程`m`。 每种情况都简化为检查派生值是否`m`是一个正整数。 

这将问题从对值的搜索转变为恒定数量的代数检查。

 ## 算法演练

 我们分别考虑这三种可能性。 

1. 假设我们进行乘法运算`a`经过`m`。 新的序列变为`[a·m, b, c]`。 要使其成为 AP，我们需要`2b = a·m + c`。 我们将其重新排列为`m = (2b - c) / a`。 这仅适用于`2b - c > 0`并可除以`a`。 
2. 假设我们进行乘法运算`b`经过`m`。 序列变为`[a, b·m, c]`。 AP条件为`2(b·m) = a + c`， 所以`m = (a + c) / (2b)`。 我们要求精确的整除性`a + c > 0`，在给定约束的情况下，这始终为真。 
3. 假设我们进行乘法运算`c`经过`m`。 序列变为`[a, b, c·m]`。 AP 条件变为`2b = a + c·m`， 所以`m = (2b - a) / c`。 我们再次要求积极性和可分割性。 

在任何时候，如果我们找到一个有效的整数`m ≥ 1`，我们可以立即返回YES。 

如果这三种情况都不能产生有效的乘数，则答案是否定的。 

### 为什么它有效

 每个有效的解决方案必须准确对应一个修改位置。 对于该固定位置，AP 条件唯一确定所需的值`m`通过线性方程。 由于只有三种可能的选择，并且每种情况都会被彻底检查，因此必须发现任何有效的配置。 相反，每个计算出的候选都直接从 AP 条件导出，因此无效配置无法通过检查。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ok(x, y, z):
    # try multiplying x by m: (x*m, y, z)
    num = 2*y - z
    if num > 0 and num % x == 0:
        m = num // x
        if m >= 1:
            return True

    # try multiplying y by m: (x, y*m, z)
    num = x + z
    if num % (2*y) == 0:
        m = num // (2*y)
        if m >= 1:
            return True

    # try multiplying z by m: (x, y, z*m)
    num = 2*y - x
    if num > 0 and num % z == 0:
        m = num // z
        if m >= 1:
            return True

    return False

t = int(input())
for _ in range(t):
    a, b, c = map(int, input().split())
    print("YES" if ok(a, b, c) else "NO")
```该代码直接实现了三个派生代数检查。 每个块对应固定一个索引作为修改元素。 整数除法检查确保我们只接受有效的乘数，并且正性条件防止无效的负解或零解。 

这里的一个常见陷阱是忘记乘数必须至少为 1。另一个微妙的问题是整数除法：我们必须在除法之前确认整除以避免错误的截断。

            if num > 0 and num % a == 0 and num // a >= 1:

 ## 边缘情况

 一种边缘情况是所有三个数字都相等。 AP 条件已经成立，将任何元素乘以`m = 1`保留它。 该算法处理这个问题是因为每种情况都允许`m = 1`，并且整除性检查自然通过。 

另一种情况是有效的解决方案需要修改中间元素。 许多不正确的解决方案都忽略了这一点，或者假设必须调整端点。 等式`m = (a + c) / (2b)`显式地捕获了这种可能性，并且整数整除性检查确保了正确性。 

最后一个微妙的情况是计算的分子变为非正数，例如`2b - c ≤ 0`。 这对应于不可能的 AP 配置，其中所选择的修改将需要非正乘数。 该算法明确拒绝这些情况，防止无效的算术解决方案被漏掉。
