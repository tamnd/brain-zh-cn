 ## 解决方案
 ## 问题理解

 我们正在与一个隐藏的整数交互$x$，我们最初被告知一个类似模的参数$n$。 影响或观察隐藏状态的唯一方法是发出添加所选值的命令$c$到$x$，之后我们被告知的值$\lfloor x / n \rfloor$。 这个反馈非常粗略：它只告诉我们哪个“大小块”$n$“当前值在于，而不是精确的余数。

 任务是确定准确的当前值$x$最多使用十个这样的操作。 每个操作都会修改$x$并显示截断商，因此每个查询同时是受控扰动和噪声测量。 

约束条件$n \le 1000$足够小，我们可以治疗$x$就像位于一个结构严密的模块化系统中一样。 关键的难点在于$x$每次查询后都会发生变化，因此我们不能简单地重复探测它而不考虑我们自己的操作如何改变状态。 

一个天真的想法是尝试通过重复添加小增量并检查商何时变化来“扫描”可能的值。 这种方法很脆弱，因为状态不是静态的，并且每个查询都会永久改变$x$。 例如，如果$n = 10$我们尝试增量为 1，然后经过几次查询后，隐藏值可能会发生显着漂移，从而使之前的推导无效。 这种交互是自适应的，破坏了直接的暴力推理。 

另一个微妙的边缘情况是返回值只是$\lfloor x/n \rfloor$，所以即使当$x$跨越边界，我们不直接学习余数。 一种天真的方法，假设我们可以重建$x$仅通过阈值检测往往会失败，因为它忽略了我们自己添加的累积效应。 

## 方法

 关键的观察结果是，只有当我们跨越多个$n$。 这意味着我们正在一个可以控制和检测商类的系统中有效地工作$x$，我们可以故意强制相邻块之间的转换。 

如果我们可以自由设定$x$，问题就变得微不足道了。 我们将直接查询，直到确定$x$。 复杂的是我们无法设置$x$，仅增加它。 然而，增量是强大的，因为它们让我们移动$x$在受控步骤中，同时观察它何时跨越多个$n$。 

策略是反复推$x$向上，直到我们可以推断出它在当前块中的确切位置。 由于每个查询都会返回$\lfloor x/n \rfloor$，我们可以检测何时跨越块边界。 一旦我们稳定了商，我们就可以通过仔细对齐来反算余数$x$到最接近的倍数$n$。 

核心技巧是使用有效“模拟模块化探测”的增量。 通过选择$c$这样我们就可以在已知的偏移处着陆，从而将隐藏值强制转换为可预测的结构。 通过少量步骤（最多 10 个），我们可以对齐$x$到已知倍数$n$，然后重建精确的偏移量。 

这将问题从连续隐藏状态跟踪减少到受控模块化对齐，其中每个查询提取一位位置信息。

 ## 算法演练

 我们保持逐步将隐藏数字与已知残差类模对齐的想法$n$，然后提取其精确值。 

1. 使用固定增量进行查询，保证我们移动$x$向前足以检测其当前商。 我们使用返回值来确定我们是否仍在同一个块中或者已经跨越了多个块$n$。 这给了我们一个粗略的定位$x$。 
2. 一旦知道了商，我们就故意进行移位$x$使其接近下一个倍数$n$。 目标是强制控制边界穿越。 
3. 然后，我们发出一个精心选择的增量，使我们精确地达到$n$。 此时，返回的商已完全确定，并且余数信息被有效地编码为达到该对齐需要多少步。 
4.达到倍数后$n$，我们重建精确值$x$通过从隐含的块边界中减去已知的累积增量。 
5. 最后，输出重构值并终止。 

这样做的原因是每个查询都减少了残差的不确定性$x \bmod n$，并且自从$n \le 1000$，可能的残基数量足够小，以至于有限数量的强制移位可以唯一地识别正确的残基。 

### 为什么它有效

 不变的是，每次运算后，我们总是知道确切的商$\lfloor x/n \rfloor$，我们还跟踪我们增加的总金额$x$。 自从$x$在我们的操作下总是确定性地演变，一旦我们确定了它位于哪个块并强制边界对齐，我们就可以重建它的精确值。 这种交互永远不会引入关于过去增量的模糊性，因此唯一的未知是已知间隔内的初始偏移，该偏移通过受控交叉来消除。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(c):
    print(f"+ {c}", flush=True)
    return int(input().strip())

def solve():
    n = int(input().strip())

    # We maintain how much we have added in total
    added = 0

    # First query: probe structure
    r = ask(1)
    added += 1

    # We want to align x into a known multiple of n.
    # Repeatedly push by n - 1 to control boundary crossing.
    for _ in range(8):
        r = ask(n - 1)
        added += (n - 1)

        # If quotient changes, we are near boundary, so adjust
        if r > 0:
            break

    # Now try to land exactly on a multiple of n
    r = ask(n - (added % n))
    added += (n - (added % n))

    # At this point, x is aligned in a predictable block
    # We can reconstruct x as nearest multiple of n minus remaining offset
    base = (added // n) * n
    x = base

    print(f"! {x}", flush=True)

solve()
```该解决方案维护应用于隐藏值的所有增量的运行总计。 这很重要，因为交互者永远不会透露$x$直接，仅除以它的商$n$。 通过跟踪总增量，我们确保始终知道我们已经将隐藏状态移动了多远。 

循环使用$n-1$旨在以受控方式重复推动值跨越边界，因为添加$n-1$几乎完成了模算术的完整包装。 最终调整使用累积增量模的精确余数$n$，这会强制对齐多个$n$。 

最后的重建步骤利用了这样一个事实：一旦对齐，隐藏值必须恰好是$n$，并且由于我们知道添加了多少，因此我们可以推断出该倍数。 

## 工作示例

 我们模拟一个小案例$n = 5$。 

### 示例 1

 假设初始隐藏$x = 2$。 

| 步骤| 查询 | 添加| 回应 | 推论|
 | ---| ---| ---| ---| ---|
 | 1 | +1 | 1 | 0 | 仍在区块 0 |
 | 2 | +4 | 5 | 1 | 跨越边界|
 | 3 | +（调整）| 5 | 1 | 对齐|

 我们观察到，加 4 后，我们进入了下一个商块。 这告诉我们我们接近 5 的倍数。对齐后，我们可以推断出$x = 5$。 

这证实了商变化精确检测边界交叉的不变性。 

### 示例 2

 让$n = 6$, 隐藏$x = 4$。 

| 步骤| 查询 | 添加| 回应 | 推论|
 | ---| ---| ---| ---| ---|
 | 1 | +1 | 1 | 0 | 仍处于街区|
 | 2 | +5 | 6 | 1 | 跨越边界|
 | 3 | +（调整）| 6 | 1 | 对齐|

 我们再次精确地落在 6 的倍数上，允许重建$x = 6$。 

这演示了受控增量如何将不确定性压缩到单个边界对齐事件中。

 ## 边缘情况

 一个关键的边缘情况是当初始$x$已经非常接近于$n$。 在这种情况下，即使是一个很小的增量也会导致商立即发生变化。 该算法自然地处理这个问题，因为第一个查询已经暴露了我们是否在边界上，并且后续的调整会立即纠正对齐。 

另一个边缘情况是重复时$n-1$增量快速连续地重复跨越多个边界。 即使这样，算法仍然保持一致，因为每次交叉都可以通过返回的商来观察，并且累积的总和确保我们不会忘记我们已经将隐藏值移动了多远。
