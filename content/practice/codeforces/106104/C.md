 ## 解决方案
 ## 问题理解

 我们从一整套大小为 N 的集合开始。每一步独立地统一从 1 到 N 中选择一个数字。 如果所选数字仍在集合中，我们将其删除； 否则该集合保持不变。 当集合变空时，该过程停止。 

我们需要预期的步数直到终止。 

输入给出多个测试用例，每个测试用例有 N，我们必须输出期望模 998244353。 

关键的观察是元素的身份从来不重要。 在任何时刻，唯一有意义的状态是剩下多少元素。 如果剩余 k 个元素，则无论它们是哪一个，系统都会表现相同。 

高达 100000 的约束 N 排除了任何指数子集 DP。 即使 O(N^2) 也太大了。 这立即暗示了一维递归或线性期望 DP。 

一个天真的想法是多次模拟该过程，但每次模拟都可能花费无限的时间，并且不会在约束内收敛。 

第二个天真的想法是独立处理每个元素并对预期移除时间求和。 这会失败，因为删除不是独立的：选择已删除的元素会消耗时间而没有进展。 

当 N = 1 时，会出现微妙的边缘情况。预期答案为 1，因为第一个选择会删除概率为 1 的唯一元素。任何公式都必须在此处正确归约。 

另一个边缘情况是 N = 2。该过程可能会“卡住”，反复挑选已删除的元素，因此期望严格大于 2。任何不正确的线性假设（例如“每个元素花费 N 个步骤”）在这里都会失败。 

## 方法

 蛮力观点是将流程状态建模为剩余元素的子集。 从大小为 k 的任何子集 S 开始，对于 S 中的某个 x，每个步骤要么以 k/N 的概率过渡到 S \ {x}，要么以 (N-k)/N 的概率停留在 S 中。 这立即定义了一个超过 2^N 状态的马尔可夫链。 

这是正确的，但不可用，因为状态空间是指数的。 即使编写过渡也已经是不可行的。 

关键的简化是大小为 k 的所有子集的行为相同。 因此，我们不跟踪子集，而是跟踪单个值 dp[k]：k 个元素仍然存活时的预期剩余时间。 

从状态 k 开始，随机选择以 k/N 的概率成功，并将 k 减少 1。以 (N-k)/N 的概率，没有任何变化，我们保持在相同的状态，这会导致额外的浪费步骤。 

这种自循环结构是关键：期望方程可以直接写出来。 

如果 E[k] 是 k 个元素的预期剩余时间，则：

 E[k] = 1 + (k/N) * E[k-1] + (1 - k/N) * E[k]

 右边反映了每一步的成本为1，然后我们要么减少状态，要么留下来。 

重新排列消除了自引用并产生了简单的递归。 

这是结构性的见解：“浪费的选秀权”不会改变状态，但它们会使时间膨胀一个取决于 k/N 的因子。 

代数之后，我们得到：

 E[k] = E[k-1] + N/k

 因此，该过程简化为对按 N 缩放的类似调和项求和。 

因此：

 E[N] = N * (1/1 + 1/2 + ... + 1/N)

 在模运算下，一切都分解为前缀谐波数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 子集上的强力马尔可夫DP | O(2^N) | O(2^N) | O(2^N) | O(2^N) | 太慢了 |
 | k 上的状态压缩 DP | O(N) | O(N) | 已接受 |

 ## 算法演练

1. 认识到仅剩余项目的数量很重要，而不是剩余的项目。 这将状态空间从子集减少到从 0 到 N 的整数 k。 
2. 将 E[k] 定义为剩余 k 个项目时所需的预期步骤数。 目标是 E[N]。 
3. 编写一个步骤的转换。 从 k 个项目中，随机选择以 k/N 的概率成功，并将 k 减少到 k−1。 否则，以 (N−k)/N 的概率，状态不会改变，但时间仍会增加一步。 
4. 将其转化为期望方程：

 E[k] = 1 + (k/N)E[k−1] + (1 − k/N)E[k]。 

左侧再次包含 E[k]，因为删除项目失败会保持状态不变。 
5. 重新排列方程以分离 E[k]。 移动 self 项给出：

 (k/N)E[k] = 1 + (k/N)E[k−1]，简化为 E[k] = E[k−1] + N/k。 
6. 使用从 E[0] = 0 开始直到 E[N] 的递归。 每一步都加上 N 乘以 i 的模逆。 
7. 保持运行谐波和 H = sum(1/i mod MOD) 并将最终答案累加为 N * H。 

### 为什么它有效

 关键的不变量是 E[k] 仅取决于 k，而不取决于剩余元素的身份。 从 k 开始的每个转换的行为都是相同的，唯一的随机性是所选索引是否仍然处于活动状态。 自循环概率产生几何等待时间效应，这正是产生加性 N/k 项的原因。 因为每个状态的减少独立于超过 k 的历史，所以递归完全表征了期望，而不会丢失信息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    t = int(input())
    inv = [0] * (100000 + 1)

    for i in range(1, 100000 + 1):
        inv[i] = modinv(i)

    for _ in range(t):
        n = int(input())
        H = 0
        for i in range(1, n + 1):
            H = (H + inv[i]) % MOD
        ans = H * n % MOD
        print(ans)

if __name__ == "__main__":
    solve()
```该实现预先计算模逆，因为相同的分母在测试用例中重复。 调和和直接累加，最终乘以 N 应用推导公式 E[N] = N * H_N。 

一个常见的陷阱是尝试迭代更新期望而不分离谐波结构。 另一个是忘记了自环项必须用代数方法消除； 如果留在原处，循环会错误地显示为圆形。 

## 工作示例

 ### 示例 1：N = 2

 我们计算倒数：1/1 = 1, 1/2 = 499122177 (mod 998244353)。 

H = 1 + 1/2。 

那么 E[2] = 2 * (1 + 1/2) = 3。 

| k | H 前缀 | E[k] |
 | ---| ---| ---|
 | 1 | 1 | 1 |
 | 2 | 1 + 1/2 | 3 |

 这表明即使对于很小的 N，期望也会超过 N，因为重复无用的抽签会使过程膨胀。 

### 示例 2：N = 3

 H = 1 + 1/2 + 1/3。 

E[3] = 3H。 

| k | H 前缀 | E[k] |
 | ---| ---| ---|
 | 1 | 1 | 1 |
 | 2 | 1 + 1/2 | 3 |
 | 3 | 1 + 1/2 + 1/3 | 1 + 1/2 + 1/3 | 3H |

 这证实了谐波贡献的线性累积。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 每个测试用例 O(N) | 谐波和超过 1..N |
 | 空间| O(1) extra（或 O(N)，如果预先计算逆）| 只需要运行总和 |

 谐波计算在运行时占主导地位，但 N ≤ 100000 确保了典型限制下的可行性。

def run(inp: str) -> str:

 ## 边缘情况

 对于 N = 1，状态开始时已经很小，并且第一个成功的选择总是立即发生。 递归给出 E[1] = N * (1) = 1，直接匹配过程。 

对于 N = 2，系统经常在已删除的元素上浪费步骤。 递归通过调和项 1/2 正确地解释了这一点，这将期望值扩大到 3。 

对于较大的 N，主要贡献来自 k 较小的后期阶段，因为 N/k 变大。 谐波结构无需模拟即可自然地捕获这种放大。
