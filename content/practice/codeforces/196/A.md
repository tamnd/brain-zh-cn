 ## 解决方案
 ## 问题理解

 我们得到一个小写字符串，并且可以选择其字符的任何非空子序列，同时保留其原始顺序。 

在所有可能的子序列中，我们需要字典顺序最大的一个。 字典比较的行为与字典顺序完全相同：两个字符串不同的第一个位置决定获胜者，如果一个字符串是另一个字符串的前缀，则较长的字符串较大。 

字符串长度可以达到$10^5$。 子序列问题立即表明指数搜索空间，因为每个字符都可以被采用或跳过。 有$2^n-1$非空子序列，当$n=10^5$。 即使重复扫描大后缀的算法如果执行的话也会变得太慢$O(n^2)$工作。 在 2 秒的限制下，我们应该以线性时间或接近线性时间为目标。 

有几种情况很容易处理不当。 

考虑：```
abc
```答案是：```
c
```粗心的方法可能会尝试保留许多字符，因为较长的字符串有时会更大。 然而，在这里，第一个字符主导了字典顺序。 任何以以下开头的子序列`a`或者`b`立即输给以`c`。 

另一个棘手的情况是：```
zzza
```答案是：```
zzza
```一旦我们决定`z`是最好的第一个字符，我们不应该只出现一次。 全部留着以后`z`字符使结果更大，因为前缀保持相等并且较长的字符串获胜。 

第三个例子是：```
ababba
```答案是：```
bbba
```仅选择第一个最大字符是不够的。 服用后`b`，我们必须在剩下的后缀上解决同样的问题并继续贪心。 

## 方法

 蛮力的想法很简单：生成每个子序列，按字典顺序比较它们，并保留最好的一个。 

这是可行的，因为问题的定义正是“找到所有子序列中的最大值”。 不幸的是，一串长度$n$有$2^n$子序列。 即使是为了$n=50$，这已经是超过千万亿的可能性了。 为了$n=10^5$，这是无望的。 

为了更快地找到东西，我们应该考虑什么决定了字典顺序。 

第一个字符是最重要的位置。 如果子序列开头为`y`，它永远无法击败以`z`。 这意味着答案的第一个字符必须是字符串中任何位置出现的最大字符。 

假设当前后缀中出现的最大字符是`c`。 任何最佳答案都必须以`c`。 出现了哪些`c`我们应该保留吗？ 

把它们全部拿走。 

如果两个候选答案以相同的前缀开头，并且其中一个以相同最大字符的额外副本继续，则较长的答案按字典顺序较大。 获得最大角色不会受到惩罚，因为它不会使较早的位置变得更糟。 

这一观察得出一个非常简单的观点。 从右到左处理字符串，同时保留迄今为止看到的最大字符。 当某个字符等于其位置处的后缀最大值时，该字符就属于答案。 

例如：```
ababba
```后缀最大值为：```
b b b b b a
```选择字符等于其后缀最大值的任何位置：```
a b a b b a
  ^   ^ ^ ^
```得到的子序列是：```
bbba
```这仅需要一次线性扫描。

 ## 算法演练

 1. 读取字符串。 
2. 从右向左遍历字符串。 
3. 维护`mx`，迄今为止在后缀中遇到的最大字符。 
4.当当前字符大于`mx`， 更新`mx`。 
5. 如果当前字符等于`mx`，将其添加到答案中。 

该字符是最大后缀。 任何最佳字典顺序最大子序列都必须包含它。 
6、收集到的字符是从右向左获取的，所以颠倒过来。 
7. 输出结果字符串。 

### 为什么它有效

 在任意位置，让`M`是出现在其右侧任何位置（包括其自身）的最大字符。 

如果当前字符小于`M`，选择它会迫使子序列以比出现以下字符时更差的字符开始`M`。 这样的选择永远不可能属于最优答案。 

如果当前字符等于`M`，跳过它也是次优的。 保留此字符会额外出现最大的可用字母，同时保留选择所有未来最佳字符的可能性。 由于当前缀相等时，字典顺序更喜欢较长的字符串，因此采用每个后缀最大字符总是有益的。 

因此，最佳子序列恰好由字符等于其后缀中最大字符的位置组成。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    mx = ''
    ans = []

    for ch in reversed(s):
        if ch > mx:
            mx = ch
        if ch == mx:
            ans.append(ch)

    print(''.join(reversed(ans)))

if __name__ == "__main__":
    solve()
```变量`mx`存储迄今为止处理的后缀中看到的最大字符。 因为我们从右向左扫描，所以这正是当前位置的后缀最大值。 

每当当前字符等于`mx`，我们保留它。 小于后缀最大值的字符将被丢弃，因为更大的字符稍后存在并主导字典顺序。 

答案以相反的顺序收集，因为扫描是从字符串的末尾向开头进行的。 最后反转一次即可恢复子序列原来的从左到右的顺序。 

不存在整数溢出问题，因为该算法仅操作字符和列表。 唯一微妙的一点是使用`if ch == mx`可能更新后`mx`。 这保证了包含新发现的最大字符数。

 ## 边缘情况

 考虑：```
abc
```从右向左扫描给出后缀最大值：```
c c c
```只有决赛`c`等于其所在位置的后缀最大值。 该算法输出：```
c
```任何以以下开头的子序列`a`或者`b`立即丢失，因为它的第一个字符较小。 

现在考虑：```
zzza
```后缀最大值为：```
z z z a
```每个字符都等于其后缀最大值，因此选择所有字符。 输出变为：```
zzza
```一个常见的错误是只保留第一次出现的最大字符和输出`z`，按字典顺序排列较小，因为`zzza`具有相同的前缀并且更长。 

最后，考虑：```
ababba
```后缀最大值为：```
b b b b b a
```选定的位置是三个`b`人物和最终`a`，生产：```
bbba
```该算法正确地跳过了两者`a`字符串中后面具有较大字符的字符。 这些位置永远不可能属于字典顺序上的最大子序列。
