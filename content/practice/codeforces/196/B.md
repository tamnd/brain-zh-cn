 ## 解决方案
 ## 问题理解

 我们有一个大小有限的迷宫`n × m`。 有些单元是墙壁，有些是开放的，一个单元包含起始位置`S`。 

迷宫不止使用一次。 相反，整个网格在每个方向上无限重复，就像用同一矩形的副本平铺平面一样。 移出一个副本后，立即进入相应位置的另一个副本。 

问题是玩家是否可以在仅踩在非墙单元上的情况下从起始位置任意远地移动。 

思考无限迷宫的一个有用方法是：

 无限平面中的每个位置对应于：

 1. 原始网格内的一个单元格。 
2. 我们当前位于网格的哪个副本中。 

两个不同的无限位置可能映射到相同的位置`(row, col)`如果它们属于图块的不同副本，则位于原始迷宫内。 

限制足够大，直接探索无限迷宫是不可能的。 原始网格最多可以包含`1500 × 1500 = 2.25 million`细胞。 任何多次重新访问单元格或存储无限多个位置信息的算法都会立即失败。 

对原始网格的图遍历仍然是可行的，因为每个原始单元格只在那里出现一次。 一个`O(nm)`或者`O(nm log(nm))`算法完全符合限制。 任何细胞数量的二次方都不会。 

棘手的部分是，重新访问相同的原始单元并不总是多余的。 达到同样的效果`(r, c)`来自不同副本的无限平铺正是创造无限运动的原因。 

考虑这个例子：```
2 2
S.
..
```正确答案是`"Yes"`。 

仅在有限网格上的朴素 BFS 会访问每个单元一次并停止，错误地得出运动是有限的结论。 事实上，没有墙，所以我们可以永远在迷宫的不同副本中行走。 

另一个微妙的情况是循环仅存在于有界区域内。```
3 3
###
#S#
#.#
```正确答案是`"No"`。 

玩家可以永远在几个单元格之间来回移动，但永远无法逃到迷宫的另一个副本。 即使图表包含循环，无限的步行距离也是不可能的。 

另一个危险的错误是错误地处理负坐标的模。 在Python中，`%`已经正确地解决了这个问题，但在许多语言中`(-1) % m`变为负数。 例如：```
1 2
S.
```从列向左移动`0`应该换行到列`1`相邻副本的。 不正确的模处理完全破坏了这种转换。 

## 方法

 最直接的想法就是按字面意思对待无限迷宫，对所有可达的坐标运行BFS或DFS`(x, y)`在飞机上。 

这在概念上是有效的，因为每个可到达的位置都可以通过普通的图遍历来探索。 如果遍历永远不会结束，那么答案是`"Yes"`。 

问题是图是无限的。 即使只存在一条小走廊，搜索也可能永远持续下去。 探索状态的数量没有有限的上限。 

关键的观察结果是迷宫模式周期性重复。 

假设我们站在无限坐标`(x, y)`。 实际的细胞类型仅取决于：```
(x mod n, y mod m)
```如此多的无限位置对应于原始网格内的同一个单元格。 

现在关键的见解来了。 

如果在遍历过程中我们到达相同的原始单元格`(r, c)`从两个不同的无限坐标，我们发现了一个穿过平铺平面的不平凡的循环。 从那时起，我们可以永远在副本之间移动，所以答案是`"Yes"`。 

为什么这有效？ 

因为两个无限坐标之间的差异代表了迷宫副本之间的平移向量。 重复相应的动作序列可以让我们漂到无限远的地方。 

这表明了正确的状态表示：

 对于每个原始网格单元，存储到达它的第一个无限坐标。 

在 DFS 或 BFS 期间：

 - 如果从未访问过该单元格，则记录其无限坐标。 
- 如果之前使用不同的无限坐标访问过单元格，我们会发现无限移动。 

这完全避免了探索无限多个状态。 在正常情况下，每个原始单元仅被处理一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 无限平面上的蛮力 | 无界| 无界| 不可能|
 | 带坐标映射的 DFS/BFS | O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 1.读取网格并找到起始单元格`S`。 
2. 从对应的无限坐标开始运行DFS或BFS`S`。 
3.对于每一个探索过的无限位置`(x, y)`，计算其对应的原始网格单元：```
rx = x % n
ry = y % m
```这告诉我们我们正站在哪个瓦片单元上。 

1. 如果映射的单元是墙，则忽略移动。 
2. 对于每个原始网格单元`(rx, ry)`，存储到达它的第一个无限坐标。 

例如：```
vis[rx][ry] = (x, y)
```1.到达时`(rx, ry)`再次：

 - 如果存储的无限坐标与`(x, y)`，这只是到同一无限位置的另一条遍历路径。 忽略它。 
- 如果存储的坐标不同于`(x, y)`，然后从迷宫的两个不同副本到达相同的原始单元格。 打印`"Yes"`立即地。 
2. 继续向四个方向遍历。 
3. 如果遍历结束时没有检测到此类冲突，则打印`"No"`。 

### 为什么它有效

 不变量是：

 对于每个原始网格单元，我们准确地记住一个可以到达它的无限坐标。 

如果我们稍后使用不同的无限坐标到达相同的原始单元，则存在一条净位移非零的路径。 重复这种位移会让我们穿过无数个迷宫。 

相反，如果不存在这种具有不同坐标的重复项，则每个可达状态恰好对应于每个原始单元格的一个无限坐标。 由于只有`nm`原始细胞，可达区域是有限的。 

这确立了两个正确方向。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

n, m = map(int, input().split())

grid = []
sx = sy = -1

for i in range(n):
    row = input().strip()
    grid.append(row)

    for j, ch in enumerate(row):
        if ch == 'S':
            sx, sy = i, j

visited = [[None] * m for _ in range(n)]

dirs = [(-1, 0), (1, 0), (0, -1), (0, 1)]

def dfs(x, y):
    rx = x % n
    ry = y % m

    if grid[rx][ry] == '#':
        return False

    if visited[rx][ry] is not None:
        px, py = visited[rx][ry]

        if px != x or py != y:
            return True

        return False

    visited[rx][ry] = (x, y)

    for dx, dy in dirs:
        nx = x + dx
        ny = y + dy

        if dfs(nx, ny):
            return True

    return False

print("Yes" if dfs(sx, sy) else "No")
```遍历在无限坐标上进行`(x, y)`，不仅在原始网格内的位置上。 这是保留有关我们正在访问的迷宫副本的信息的核心思想。 

模运算将每个无限坐标映射回原始图块：```
rx = x % n
ry = y % m
```Python 的模数已经可以正确处理负数，这在移动穿过顶部或左侧边界时至关重要。 

这`visited`数组不存储布尔值。 它存储首先到达每个原始网格单元的精确无限坐标。 这种区别就是整个解决方案。 

认为`(2, 3)`首先从无限坐标到达图块内部`(2, 3)`。 如果我们稍后到达相同的瓦片单元格`(2 + n, 3)`，那么我们就知道穿越进入了另一个迷宫副本。 

一旦出现这种冲突，DFS就会立即停止。 

一个很容易出错的实现细节是重新访问完全相同的无限坐标。 这是无害的，不应触发`"Yes"`。 

这个条件是重要的检查：```
if px != x or py != y:
    return True
```由于可到达的组件可能在长链中包含数百万个单元，因此增加了递归限制。

 | ---| ---| ---|
 | 时间 | O(纳米) | 每个原始网格单元在终止或拒绝之前最多处理一次 |
 | 空间| O(纳米) | 访问的表每个单元格存储一个坐标对 |

 网格最多包含`2.25 million`细胞，因此线性复杂度是必要的。 该解决方案仅对每个可到达的单元执行恒定的工作，并且在限制范围内舒适地适应。

 ## 边缘情况

 考虑尽可能最小的网格：```
1 1
S
```单个细胞在各个方向上无限重复。 开始于`(0,0)`，向上移动达到`(-1,0)`，映射回`(0,0)`。 

该算法首先存储：```
visited[0][0] = (0,0)
```后来达到：```
(-1,0)
```它映射到相同的图块单元，但具有不同的无限坐标。 算法正确打印`"Yes"`。 

现在考虑一个捕获配置：```
3 3
###
#S#
###
```DFS 只探索`(1,1)`。 每个相邻单元在模映射后都是一堵墙。 没有第二个无限坐标到达同一个图块单元，因此遍历结束，答案是`"No"`。 

最后，考虑通过负坐标进行换行：```
1 2
S.
```向左移动自`(0,0)`给出`(0,-1)`。 Python 计算：```
-1 % 2 == 1
```所以映射的位置变成`(0,1)`，正是左侧副本中的相邻平铺单元格。 

不正确的模处理可能会崩溃或映射到无效列，从而产生错误的答案。
