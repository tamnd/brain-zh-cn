[CF 271D - 好的子串](https://codeforces.com/problemset/problem/271/D)

 ## 解决方案
 ## 问题理解

 我们得到一个由小写英文字母组成的字符串。 每个字母都使用单独的 26 字符二​​进制掩码标记为好或坏。 我们还得到一个整数 k，它限制了子字符串中允许容忍的坏字母数量。 

当我们查看某个子串的字符时，如果其中坏字母的数量不超过 k，则该子串是有效的。 任务不是计算所有有效子字符串，而是计算这些有效子字符串中出现了多少个不同的字符串。 

因此，如果从不同位置获取的两个子字符串的字符序列相同，则认为它们是相同的。 例如，在像“abab”这样的重复字符串中，“ab”的不同出现仅计数一次。 

字符串长度最多为 1500，这立即表明对子字符串进行 O(n²) 枚举是可行的，因为 n² 约为 225 万。 任何依赖于单独检查所有子字符串并在每个子字符串中进行线性工作的解决方案仍然会面临大约 10⁹ 操作的风险，这太慢了。 

主要困难是“不同子串”的要求以及对坏字符的限制。 

一些边缘情况很重要。 

如果 k 为零并且所有字符都是坏字符，则只应计算好的单字符子字符串，并且重复项仍必须折叠为每个唯一字母一个。 

如果 k 足够大以覆盖整个字符串，那么问题就简化为计算 s 的所有不同子字符串。 

一个幼稚的错误是仅根据有效性来计算子字符串而忘记了唯一性，这在像“aaaaa”这样的重复字符串中会严重过度计算。 

另一个错误是尝试先过滤子字符串，然后将它们插入到集合中而不控制复杂性，这可能会由于重复的子字符串提取而导致 O(n3) 行为。 

## 方法

 暴力方法很简单。 我们枚举所有子串 s[l..r]。 对于每个子字符串，我们计算它包含多少个错误字符。 如果该计数最多为 k，则我们将子字符串插入到一组字符串中。 

这是正确的，因为它完全按照规定检查条件。 问题是性能。 有 O(n²) 个子字符串，提取每个子字符串并天真地计算坏字符需要 O(n)，从而导致 O(n³)。 即使坏计数的前缀和将检查减少到 O(1)，子字符串提取和散列仍然使 Python 中的总工作量围绕 O(n³) 个字符操作，这对于 n = 1500 来说太慢了。 

关键的观察是我们不需要通过重复构建字符串来显式计算所有子字符串。 相反，我们可以利用小字母表并在子字符串上使用滚动哈希结构。 我们还可以重复使用前缀和来计算错误字符数，因此有效性检查的时间复杂度为 O(1)。 

最终的想法是迭代所有起始位置l。 对于每个 l，我们将 r 从 l 扩展到 n-1，保持 s[l..r] 中坏字符的数量。 一旦超过 k，我们就停止扩展这个 l，因为添加更多字符只会增加错误计数。 在扩展时，我们计算子字符串的滚动哈希，以便我们可以在 O(1) 摊余时间内将每个有效子字符串存储在集合中。 

这将问题减少到 O(n²) 次扩展，每个扩展都有 O(1) 更新，这是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（子串+每次计数）| O(n3) | O(n) | 太慢了 |
 | 最优（两个循环+前缀+滚动哈希）| O(n²) | O(n²) | 已接受 |

 ## 算法演练

 我们使用布尔数组预先计算哪些字母是错误的。 我们还构建了一个前缀和数组，以便我们可以在恒定时间内计算任何子字符串中的坏字符数。 

然后，我们枚举所有起始位置并将子字符串向右扩展，同时跟踪有效性和散列。 

### 步骤

1. 构建一个数组 bad[c] ，表示字符 c 是否为坏字符。 这允许对每个字符进行恒定时间分类。 
2. 构建前缀和数组 pref，其中 pref[i] 是 s[0..i-1] 中的坏字符数。 这让我们可以将任何子字符串中的错误计数计算为 pref[r+1] - pref[l]。 
3. 准备滚动哈希基并预先计算基的幂。 这允许我们在扩展 r 时增量计算 hash(s[l..r])。 
4. 创建一个空集，它将存储所有有效子字符串的哈希值。 该集合确保我们只对不同的子字符串进行一次计数。 
5. 对于每个起始索引 l，初始化 hash = 0 和 bad_count = 0。 
6. 对于从 l 到 n-1 的每个 r，更新 bad_count 和 hash 以包含 s[r]。 如果 bad_count 超过 k，则跳出该 l 的循环，因为进一步扩展只会增加 bad_count。 
7. 如果子字符串有效，则将其哈希值插入到 saw 中。 
8.处理完所有l后，答案就是看到的大小。 

### 为什么它有效

 关键的不变量是，对于每对 (l, r)，我们维护 s[l..r] 的准确哈希值以及该子字符串中坏字符的准确数量。 我们仅在满足约束时插入子字符串，并且每个有效子字符串都作为 (l, r) 对访问一次。 由于不同的子串是通过其散列来标识的，并且在足够大的模数下冲突可以忽略不计（或通过双重散列来避免），因此设置的基数与不同的有效子串的数量相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    mask = input().strip()
    k = int(input().strip())
    
    n = len(s)
    
    bad = [0] * 26
    for i in range(26):
        bad[i] = (mask[i] == '0')
    
    base = 91138233
    mod = (1 << 61) - 1

    def modmul(a, b):
        return (a * b) % mod

    pref_bad = [0] * (n + 1)
    for i in range(n):
        pref_bad[i + 1] = pref_bad[i] + bad[ord(s[i]) - 97]

    pow_base = [1] * (n + 1)
    for i in range(n):
        pow_base[i + 1] = modmul(pow_base[i], base)

    seen = set()

    for l in range(n):
        h = 0
        bad_cnt = 0
        for r in range(l, n):
            c = ord(s[r]) - 97
            bad_cnt += bad[c]
            if bad_cnt > k:
                break
            h = modmul(h, base) + (c + 1)
            h %= mod
            seen.add(h)

    print(len(seen))

if __name__ == "__main__":
    solve()
```该代码构建滚动哈希，同时从其左端点扩展每个子字符串。 哈希更新将先前的值乘以基数并添加新的字符代码，确保不同的子字符串以非常高的概率映射到不同的值。 

计算前缀和数组，但在最终实现中并不严格要求，因为我们增量地维护错误计数，但它作为正确性参考和替代方法很有用。 

一个微妙的点是，一旦超过不良字符限制，我们就会提前中断。 这可以防止当 k 很小时内循环退化为对所有 l 进行完整的 n 长度扫描。

 ## 边缘情况

 关键的边缘情况是当 k = 0 并且字符串包含许多错误字符时。 在这种情况下，每个起始位置只允许非常短的扩展，通常长度为 1。该算法会处理此问题，因为一旦出现第二个坏字符，bad_cnt 就会立即超过 k，从而导致内部循环提前终止。 

另一种情况是高度重复的字符串，例如“aaaaa”。 如果没有集合，我们就会多次过度计算相同的子串。 该集合确保每个子字符串（如“a”、“aa”、“aaa”）仅计算一次，无论有多少个位置生成它。 

最后的边缘情况是所有字符都很好并且 k 很大。 内部循环永远不会提前中断，我们生成所有子字符串，但仍然只通过散列存储不同的子字符串。 这会执行完整的 O(n²) 路径，确认性能仍然可以接受。
