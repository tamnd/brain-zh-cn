 ## 解决方案
 ## 问题理解

 我们得到一个正整数网格。 从这个网格中，我们可以重复选择任何单个单元格并将其值加一。 每增加一次就要花费一次移动。 目标是使网格成为“素数”，即至少一整行变为素值，或者至少一整列变为素值。 

仅当某个值成为素数时，该值在所选行或列中才是可接受的。 由于我们只能增加值，因此每个单元格都有一个独立的成本：将其变成大于或等于其当前值的素数所需的增量数。 

任务是选择一行或一列，并支付将其中的每个值转换为素数的总成本，然后最小化所有行和列的成本。 

约束最大为 500 x 500 网格，因此单元格数量最多为 250,000 个。 每个值最多为 100,000，但可以任意递增。 这立即表明任何每个单元的大量计算都必须进行预处理，因为在嵌套循环内重复重新计算素数距离仍然会通过，但前提是素性检查有效且可重用。 

一个微妙的边缘情况是当某些行或列中的数字已经是质数时。 该行或列的成本为零，答案也为零。 另一个重要的情况是，当许多值略低于素数时，例如 14、20、26。如果在循环内重复执行，每个单元格“通过逐一递增来检查下一个素数”的天真的做法会太慢。 

关键的隐藏要求是，对于网格中的每个数字，我们必须有效地计算大于或等于它的最小素数。 

## 方法

 暴力方法将独立处理每一行和每一列。 对于固定行，我们将迭代其所有单元格，并对每个单元格重复递增，直到达到质数，对增量求和。 然后我们对每一列重复相同的操作并取最小值。 

这是正确的，但速度太慢，因为每个单元格可能需要多次增量，而我们对最多 250,000 个单元格执行此操作。 在最坏的情况下，如果值接近 100,000 并且素数在本地稀疏，则每个增量的重复素数检查将导致数十亿次检查。 

关键的观察结果是，每个单元的成本是独立的，仅取决于其价值。 我们不需要模拟增量。 相反，我们预先计算每个整数的下一个素数，直到略高于 100,000 的安全限制。 那么每个单元贡献一个固定成本：`next_prime[a[i][j]] - a[i][j]`。 

一旦我们有了这个成本网格，问题就减少到寻找所有行和所有列的最小总和。 这只是预先计算值的聚合。 

因此，解决方案结构变为：使用筛子预先计算素数，构建下一个素数数组，计算每个单元的成本，然后计算行总和和列总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力增量模拟| O(nm × 步数) | O(1) | O(1) | 太慢了 |
 | 筛选+预计算+聚合| O(MAX log log MAX + nm) | O(MAX log log MAX + nm) | O(最大) | 已接受 |

 ## 算法演练

 1. 选择略高于最大可能值的最大界限，通常为 100000 + 边距（例如 130000）。 这确保每个数字上面都有一个可达素数。 
2. 运行埃拉托斯特尼筛法来标记所有素数直至该界限。 这提供了恒定时间的素性查找。 
3. 构建数组`next_prime`这样对于每个整数 x，`next_prime[x]`是大于或等于 x 的最小素数。 

这是通过从最大值向下扫描同时记住最后看到的素数来完成的。 
4. 隐式创建成本矩阵：对于每个单元 (i, j)，计算`cost[i][j] = next_prime[a[i][j]] - a[i][j]`。 这表示该单元格所需的最小增量数。 
5. 通过对每行的单元成本求和来计算每行的成本。 
6. 类似地计算每列的成本。 
7. 返回所有行总和和列总和中的最小值。 

每一步都将问题从动态增量操作简化为静态预计算差异，这是核心简化。 

### 为什么它有效

 每个单元格独立地影响行或列是否完全素数。 由于不同单元上的操作不会相互作用，因此转换一行的成本只是各个最小成本的总和。 因为我们总是选择每个值上方最接近的素数，所以我们永远不会为每个单元多付钱。 这保证了计算的任何行或列成本都是该结构的真正的最小成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXV = 130000

# sieve
is_prime = [True] * (MAXV + 1)
is_prime[0] = is_prime[1] = False

for i in range(2, int(MAXV ** 0.5) + 1):
    if is_prime[i]:
        step = i
        start = i * i
        for j in range(start, MAXV + 1, step):
            is_prime[j] = False

# build next prime
next_prime = [0] * (MAXV + 2)
last = -1
for i in range(MAXV, -1, -1):
    if is_prime[i]:
        last = i
    next_prime[i] = last

n, m = map(int, input().split())
a = [list(map(int, input().split())) for _ in range(n)]

row_cost = [0] * n
col_cost = [0] * m

for i in range(n):
    for j in range(m):
        v = a[i][j]
        cost = next_prime[v] - v
        row_cost[i] += cost
        col_cost[j] += cost

ans = min(min(row_cost), min(col_cost))
print(ans)
```筛子部分确保我们可以立即确定素数，并导出任何值的下一个素数。 反向扫描至关重要，因为它将稀疏素数分布转变为直接查找表。 

矩阵上的嵌套循环对每个单元计算一次成本，并同时累加行和列总计，从而避免额外的传递。 

一个微妙的点是我们依赖`next_prime[v]`永远存在。 这就是为什么筛子范围必须足够大，超出最大输入值。

 ## 边缘情况

 关键的边缘情况是矩阵已经包含完整的素数行或列。 例如，如果一行是`[2, 3, 5]`，其成本变为零，答案必然为零。 该算法处理这个问题是因为`next_prime[p] - p`为零时`p`是质数，因此行总和自动为零。 

另一种情况是多行和多列并列时。 例如，全为 1 的统一矩阵会产生相同的行和列成本。 该算法独立地正确计算所有总和并取最小值，而不假设唯一性。 

第三种情况是当值正好位于素数下方时，例如 14、20、26。每个单元格独立跳转到其最近的素数 (17、23、29)。 由于每个成本都是局部的，因此求和不会干扰全局结构，并且行和列评估保持一致。 

最后，筛边界必须足够高。 如果太小，`next_prime[x]`对于较大的值可能是未定义的，从而产生不正确的结果。 固定的上限确保每个输入值都有一个有效的下一个素数。
