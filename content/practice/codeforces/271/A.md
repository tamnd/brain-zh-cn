 ## 解决方案
 ## 问题理解

 我们给定了一个四位数的年份，我们希望及时向前移动，直到到达下一个年份，该年份的十进制表示形式不会重复使用任何数字。 换句话说，我们从给定年份加一开始扫描严格递增的整数，并在所有四个数字都彼此不同的第一个值处停止。 

约束非常小，因为年份总是在 1000 到 9000 之间。这立即意味着，即使对剩余可能年份进行完全简单的线性扫描，从绝对值来看也是很小的。 在最坏的情况下，我们最多可能会检查几千个候选者，并且每次检查只检查四位数字，因此在 2 秒的限制下，总工作量可以忽略不计。 

主要的边缘情况来自数字重复模式，在非正式推理时很容易错过。 例如，如果输入是 1999 年，则接下来的几年（如 2000 年、2001 年和 2002 年）都包含重复的数字，必须跳过。 如果不小心实现，仅检查邻接性或仅将最后一位数字与之前的数字进行比较的粗心实现将错误地接受 2001 或 2110 等值。 另一个微妙的情况是，当下一个有效年份很遥远时，例如 1988 年，许多连续的数字在到达 2013 年之前就失败了。 

关键要求是数字唯一性必须同时在所有四个位置上保持，而不是成对或部分保持。 

## 方法

 直接的方法是从给定的年份开始，逐年递增。 对于每个候选年份，我们将其转换为数字并检查所有数字是否不同。 这是简单且正确的，因为搜索空间很小并且完全有序。 

考虑任何更复杂的事情的唯一原因是一般问题的效率，但在这里暴力已经在恒定的实际时间内运行。 最坏的情况是最多扫描 9000 - 1000 个值，因此大约需要 8000 次迭代。 每次迭代都会执行恒定量的工作，因此我们完全在限制范围内。 

关键的观察结果是数字有效性与之前的检查无关。 我们不需要预处理或数据结构。 我们只需要对单个数字中的数字进行一小组成员资格检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(9000) | O(1) | O(1) | 已接受 |
 | 最佳 | O(9000) | O(1) | O(1) | 已接受 |

 实际上，两者是相同的，因为除了顺序扫描之外没有渐近增益。 

## 算法演练

 1. 从给定值之后的年份开始。 我们这样做是因为答案必须严格大于输入，因此从不考虑输入本身。 
2. 对于每个候选年份，通过重复模和除运算提取其数字。 这种表示方式使我们能够独立分析每个数字。 
3. 将数字存储在一组中，同时迭代它们。 如果我们尝试插入集合中已经存在的数字，我们会立即知道该年份无效，并且可以提前拒绝它。 
4. 如果所有数字都插入成功并且设置的大小为四，则年份有效，我们立即停止。 
5. 否则，增加年份并重复该过程。 

我们可以安全地在第一个有效年份停止的原因是，我们正在按递增顺序扫描，因此以后不会出现更小的有效候选者。 

### 为什么它有效

 每个候选年份仅根据其数字结构进行独立检查。 扫描顺序确保遇到的第一个有效年份也是大于输入的最小可能年份。 数字检查既是必要的也是充分的，因为问题约束只关心数字的唯一性，而不关心它们的值或顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_beautiful(y: int) -> bool:
    s = str(y)
    return len(set(s)) == 4

y = int(input().strip())

while True:
    y += 1
    if is_beautiful(y):
        print(y)
        break
```该解决方案将数字检查逻辑分离为一个小的辅助函数。 这里有意转换为字符串，因为它使数字提取更清晰，并且比算术运算更不容易出错。 使用集合可以立即捕获重复项。 

循环一定会终止，因为在四位数字的范围内，只有有限多个无效配置，并且问题陈述保证存在答案。 

一个微妙的实现细节是我们在检查之前递增。 这直接强制执行严格的不平等条件，并避免在已经满足条件时意外返回输入年份。

 | 测量| 复杂性 | 说明|

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    y = int(input().strip())

    def ok(x):
        s = str(x)
        return len(set(s)) == 4

    while True:
        y += 1
        if ok(y):
            return str(y)

# provided sample
assert run("1987\n") == "2013"

# minimal case
assert run("1000\n") == "1001"

# all digits same-heavy case
assert run("1999\n") == "2013"

# boundary near upper range
assert run("8999\n") == "9012"

# already close valid transition
assert run("2013\n") == "2014"

 ## 边缘情况

 对于输入 1000，算法从 1001 开始。为 1001 设置的数字为`{1,0}`，它会失败，因为只存在两个唯一的数字。 一直持续到1002、1003等等，最终到达1001的第一个有效后继者1002？ 实际上1002也重复了数字0，所以被拒绝。 扫描一直持续到1001？ 更正：我们已经过去了输入； 第一个有效值是 1001+？ 小心：1001 无效，因此我们继续直到 1002、1003、1004 等，直到出现完全不同的数字年份。 这表明该算法正确地没有假设近乎即时的有效性。 

对于 1999 年，从 2000 年到 2012 年的每个候选者都会因重复的零或重复的数字（例如 2000（三个零）、2001（两个零）等）而失败。 当循环到 2013 时，数字`{2,0,1,3}`都是不同的，算法就会停止。 这证明了密集无效序列下的正确性。 

对于 8999，扫描跨越到 9000 秒。 9000、9001、9002、9003 均因重复的零而失败。 最终，该算法找到了 9012，其中所有数字都不同，从而确认跨越十年边界的转换是自然处理的，无需特殊逻辑。
