 ## 解决方案
 # 问题理解

 我们有一个游戏`n`水平。 精加工水平`i`永久地给我们物品`i`。 在任何时候，对正常游戏玩法唯一重要的物品是我们收集的最大编号的物品，因为每个较大的物品永远不会比较小的物品更差。 

对于每个级别，我们知道两种完成时间。 正常时间`a[i][j]`是完成关卡的时间`i`携带物品时`j`。 快捷时间`s[i]`仅当我们已经拥有特定的快捷方式项目时才能使用`x[i]`。 目标是选择完成关卡的顺序，以使所有完成时间的总和尽可能小。 

约束条件`n <= 2500`是关键的限制。 一个算法`n^2`操作是可以接受的，提供大约六百万个转换。 枚举阶数或维护任意子集的方法是不可能的，因为可能状态的数量呈指数增长。 即使许多适用于所有可能的有向边的图算法，如果它们需要的不仅仅是二次工作，也会太昂贵。 

主要的隐藏结构是当前库存可以通过单个数字来概括，即获得的最大项目。 以比当前最大值更小的指数完成关卡永远不会提高未来的可能性。 这样的水平只会带来成本并且可以延迟。 改变未来选项的唯一级别是增加当前最大项目的级别。 

粗心的解决方案可能会以多种方式失败。 考虑这个输入：```
2
2 1 10 10 1
2 11 11 11 11
```最优答案是`12`。 我们首先及时完成第 2 级`11`，然后使用项目 2 及时完成关卡 1`1`。 总是首先完成当前最便宜的级别的贪婪策略选择级别 1，花费`10`，然后支付`11`对于 2 级，给予`21`。 错误在于忽略了稍微贵一点的关卡可以解锁更便宜的未来关卡。 

另一个常见的错误是假设索引较小的每个级别应在可用后立即完成。 例如：```
2
0 5 5 5 5
0 7 7 7 7
```答案是`12`。 先完成第 1 级或先完成第 2 级都可以，因为两者都不会为对方创造更好的物品。 该算法必须允许对级别进行任意排序，而不会增加最大项目。 

## 方法

 直接方法会尝试所有可能的完成级别顺序。 这是正确的，因为每个有效订单都代表可能的速度运行，但也有`n!`可能的订单，即使是非常小的订单也是不可能的`n`。 

更合理的尝试是将过程建模为从当前完成的集合中选择下一个级别。 这仍然遗漏了重要的结构。 完成的集合可以包含许多级别，但从未来进度的角度来看，最大项目以下的所有级别都是等效的。 唯一有意义的状态信息是迄今为止获得的最大项目。 

假设当前最大项是`m`。 索引小于或等于的任何未完成的级别`m`无法增加最大值，因此提前完成它无法解锁任何东西。 我们可以将所有此类级别推迟到最后。 唯一重要的决定是我们获得哪些更大的指数以及以什么顺序获得。 

这将问题转换为索引上的最短路径问题。 从最大项目的过渡`m`到更大的层面`i`意味着这个级别`i`是下一个新的最大值。 过渡成本正是完成关卡所需的时间`i`当有物品时`m`。 自从`i`必须大于`m`，所有转换都继续进行，创建 DAG。 

达到最大物品数后`n`，不可能有进一步的进展。 使用物品完成剩余的每个级别`n`，这始终是最强的项目。 最终的清理成本只是尚未选择为最大步骤的所有级别的成本之和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解订单 | O(n!) | O(n) | 太慢了 |
 | 增加最大项目数的动态规划 | O(n²) | O(n) | 已接受 |

 ## 算法演练

 1. 计算最大项目之间每次转换的最小成本。 对于每个可能的电流最大值`j`和每个级别`i > j`，过渡成本是完成关卡所需的时间`i`拥有物品时`j`。 仅当以下情况时才包含快捷方式`x[i] <= j`，因为只有那时其所需的项目才已经可用。 
2. 使用动态规划`dp[i]`是达到项目状态所需的最短时间`i`是获得的最大的项目。 初始状态是`dp[0] = 0`，因为项目 0 从一开始就可用。 
3. 处理从小索引到大索引的最大项目。 来自一个州`j`，尝试每个更大的级别`i`作为下一个最大项目并放松`dp[i]`和`dp[j] + cost(j, i)`。 该顺序是有效的，因为所有转换都从较小的索引移动到较大的索引。 
4. 找到到达物品的最低成本后`n`，添加完成未用作最大增加步骤的每个级别的成本。 更简单的方法是观察到达的项目`n`始终是最优路径的一部分，并且最终的过渡路径已经为级别付出了代价`n`。 然后可以使用 item 来完成所有其他级别`n`按成本`min(a[i][n], s[i] if x[i] <= n)`。 由于项目`n`始终可用，这将成为每个剩余级别的最低可能成本。 

为什么有效：获得的最大项目是对未来进度的完整描述。 低于当前最大值的任何级别只会消耗时间并且无法更改可用项目，因此提前移动它无法改进解决方案。 每个最佳速度通关都可以转化为仅首先考虑增加最大物品的级别。 这些最大增加级别形成严格增加的序列，并且动态规划考虑每个这样的序列。 一旦获得最大的物品，每个剩余的级别都有其各自最便宜的可能完成时间，因此最终的清理是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    x = [0] * (n + 1)
    s = [0] * (n + 1)
    a = [[0] * (n + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        data = list(map(int, input().split()))
        x[i], s[i] = data[0], data[1]
        for j in range(n + 1):
            a[i][j] = data[2 + j]

    dp = [10**30] * (n + 1)
    dp[0] = 0

    for cur in range(n):
        if dp[cur] == 10**30:
            continue
        for nxt in range(cur + 1, n + 1):
            cost = a[nxt][cur]
            if x[nxt] <= cur:
                cost = min(cost, s[nxt])
            if dp[nxt] > dp[cur] + cost:
                dp[nxt] = dp[cur] + cost

    ans = dp[n]
    used = [False] * (n + 1)
    cur = n
    while cur != 0:
        found = False
        for prev in range(cur):
            cost = a[cur][prev]
            if x[cur] <= prev:
                cost = min(cost, s[cur])
            if dp[prev] + cost == dp[cur]:
                used[cur] = True
                cur = prev
                found = True
                break
        if not found:
            break

    for i in range(1, n + 1):
        if not used[i]:
            cost = a[i][n]
            if x[i] <= n:
                cost = min(cost, s[i])
            ans += cost

    print(ans)

if __name__ == "__main__":
    solve()
```输入使用基于 1 的索引存储，因为项目编号与级别编号匹配。 动态编程数组仅表示当前最大项，而不是已完成级别的整个集合。 

转换循环仅尝试`nxt > cur`。 这是该解决方案的核心属性。 只有当一个级别的索引大于当前最大值时，该级别才能成为新的最大值，因此所有有用的进度都形成一个递增序列。 

快捷方式检查使用`x[nxt] <= cur`。 此情况表示快捷方式项目已被收集。 由于当前状态仅存储最大项，因此索引较小的每个项也保证可用。 

重建步骤标记了用于增加最大值的级别。 剩余的级别使用 item 添加在最后`n`，因为项目`n`主导所有其他项目。 Python 整数是任意精度的，因此大可能的答案不需要特殊处理。 

## 工作示例

 对于第一个样本：```
3
1 1 40 30 20 10
3 1 95 95 95 10
2 1 95 50 30 20
```重要的状态是：

 | 当前最大值| 下一个最大值 | 过渡成本| 新的 dp 值 |
 | --- | --- | --- | --- |
 | 0 | 1 | 40| 40|
 | 0 | 2 | 95 | 95 95 | 95
 | 0 | 3 | 95 | 95 95 | 95
 | 1 | 2 | 50 | 50 90 | 90
 | 1 | 3 | 50 | 50 90 | 90
 | 2 | 3 | 20 | 115 | 115

 到达第 3 项的最佳路径有成本`90`，使用级别 1 和 3 作为递增序列。 然后及时完成第 2 级第 3 项`1`，给出答案`91`。 

对于第二个样本：```
4
4 4 5 5 5 5 5
4 4 5 5 5 5 5
4 4 5 5 5 5 5
4 4 5 5 5 5 5
```有用的转换是：

 | 当前最大值| 下一个最大值 | 过渡成本| 新的 dp 值 |
 | --- | --- | --- | --- |
 | 0 | 1 | 5 | 5 |
 | 0 | 2 | 5 | 5 |
 | 0 | 3 | 5 | 5 |
 | 0 | 4 | 5 | 5 |

 获得第 4 项后，剩余的每一级都会花费`4`因为快捷方式项目 4 现在可用。 最佳顺序是先获得第 4 级，然后完成其他三个级别，给出`5 + 4 + 4 + 4 = 17`。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n²) | 每对可能增加的最大项都会被考虑一次。 |
 | 空间| O(n²) | 输入完成表需要存储`n * (n + 1)`价值观。 |

 和`n = 2500`，二次转换次数约为 625 万次，完全符合时间限制。 该表包含大约 625 万个整数，只有仔细实现才不会超出 Python 的内存限制。 提供的实现存储完整的表，因为输入大小需要访问任意`a[i][j]`转换期间的值。

 ## 边缘情况

 对于更昂贵的第一步解锁更便宜的未来动作的情况：```
2
2 1 10 10 1
2 11 11 11 11
```动态规划并不致力于最便宜的直接级别。 它考虑了从第 0 项的两种转换。到第 2 项的转换成本`11`，达到最强的物品，并留下最终成本的 1 级`1`，生产`12`。 

对于除了通过一个大索引之外从不增加最大值的级别：```
3
3 1 100 100 100 1
3 2 100 100 100 2
3 3 100 100 100 3
```最好的路线是先到达第 3 项。 之后，每个剩余级别都可以使用快捷方式项 3。动态规划捕获单个有用的最大增量，清理阶段添加剩余的最优成本。 结果是`6`。 

对于需要第 0 项的快捷方式：```
2
0 5 5 5 5
0 7 7 7 7
```项目 0 从一开始就存在，因此两个快捷键都可以立即使用。 在收集任何其他项目之前，转移成本已正确减少，答案是`12`。
