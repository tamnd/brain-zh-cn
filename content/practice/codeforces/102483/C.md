 ## 解决方案
 # 问题理解

 输入将电路描述为树。 每个顶点都是一个连接点，每条边都是一条必须绘制为直线段的线。 任务不是找到路径或优化成本，而是为每个顶点分配一个坐标，以便可以在平面上物理打印给定的树。 

该结构具有严格的几何要求。 每个树边必须成为长度正好为一的线段。 两条不相关的边不能交叉，不同的顶点也不能靠得太近。 由于棋盘很大，因此面临的挑战是找到一种系统的方法来在不违反几何形状的情况下展开树。 

顶点数最多为 1000 个。这个值足够小，可以进行线性或接近线性的遍历，但对于尝试许多可能的布局来说又太大了。 组合探索不同角度或位置的方法将远远超出可用时间。 树结构是使简单的递归构造成为可能的关键限制。 

有几种情况可能会因粗心的实施而被破坏。 单边是可能的最小树：```
2
1 2
```有效答案是相距一个单位的任意两点，例如`(0,0)`和`(1,0)`。 假设每个顶点都有子节点的实现在这里可能会失败。 

星形树是另一个重要的例子：```
5
1 2
1 3
1 4
1 5
```该中心有很多孩子。 将所有子项放置在太近的角度可能会导致边重叠或将不同的顶点几乎放在彼此的顶部。 

长链也很重要：```
4
1 2
2 3
3 4
```重复使用固定侧向的方法可能会意外地将所有顶点放置在彼此的顶部或创建重叠的线段。 递归放置必须处理只有一个子节点的顶点以及分支节点。 

# 方法

 一种直接的方法是尝试将顶点一个接一个地放置，同时检查新边是否与现有边相交。 对于每一个新点，我们都可以在多种可能的角度中寻找自由的方向，并拒绝产生冲突的选择。 这适用于非常小的树，因为树只有`n - 1`边缘，但候选布局的数量增长很快。 在最坏的情况下，针对所有先前的边缘重复检查许多位置会导致大致二次或更糟糕的工作，并且搜索本身没有简单的界限。 

蛮力之所以有效，是因为树没有循环，所以我们可以自由地从根向外构建绘图。 它失败了，因为它试图在做出任意选择后局部解决几何问题。 

有用的观察是，可以在角区域内绘制有根树。 如果一个顶点拥有方向楔，则其所有后代都可以放置在该楔内。 同一顶点的子树可以接收不相交的子楔，因此它们的子树永远不需要交叉。 树属性正是允许这种递归分离的原因。 

我们对树求根并计算每个子树的大小。 当在子树之间分配可用角度时，较大的子树接收更大的角度范围。 确切的比例并不重要，但给每个孩子足够的空间可以使更深的递归绘图分开。 每个子项都被放置在距离其父项恰好一个单位的指定角度间隔的中间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每次尝试的布局为 O(n²)，尝试次数没有有用的限制 | O(n) | 太慢而且不可靠 |
 | 最佳 | O(n) | O(n) | 已接受 |

 # 算法演练

 1. 以顶点 1 为树根并计算每个子树的大小。 子树大小告诉我们一个子树与其兄弟姐妹相比应该接收多少角度空间。 
2. 从根目录开始`(0, 0)`并给出完整的可能方向。 递归调用存储从父节点到当前顶点的方向以及当前子树可用的角度间隔。 
3. 对于一个顶点，查看除其父节点之外的所有子节点。 根据子树大小按比例分割子节点之间的可用间隔。 孩子接收其间隔的中间方向。 
4. 使用该方向将子项放置在距当前顶点 1 个单位的位置。 这会自动满足边长要求。 
5. 以自己的角度间隔递归到子级。 子级仅在为其后代保留的间隔内分配空间，因此不同的分支保持分离。 

将子级放置在与父级边相反的方向的原因是父级边占据顶点的一侧。 剩余的角度空间是为孩子们保留的。 

为什么它有效：每个递归调用都拥有一个楔形，其中包含该顶点下方的整个子树。 兄弟楔块不重叠，因此它们的边不能交叉。 兄弟子树之间唯一的共享点是它们的父树。 每个递归放置都使用单位向量，因此每条边的长度均为一。 该结构从根部到每片叶子都保持了这些特性。 

# Python 解决方案```python
import sys
import math

input = sys.stdin.readline

n = int(input())
g = [[] for _ in range(n)]

for _ in range(n - 1):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    g[a].append(b)
    g[b].append(a)

size = [0] * n
parent = [-1] * n

def calc(v, p):
    parent[v] = p
    size[v] = 1
    for u in g[v]:
        if u != p:
            calc(u, v)
            size[v] += size[u]

calc(0, -1)

ans = [(0.0, 0.0)] * n

def build(v, p, x, y, direction, width):
    children = [u for u in g[v] if u != p]
    if not children:
        return

    total = sum(size[u] for u in children)
    start = direction + math.pi - width / 2

    for u in children:
        part = width * size[u] / total
        mid = start + part / 2

        nx = x + math.cos(mid)
        ny = y + math.sin(mid)
        ans[u] = (nx, ny)

        build(u, v, nx, ny, mid, part)
        start += part

build(0, -1, 0.0, 0.0, 0.0, 2 * math.pi)

for x, y in ans:
    print("{:.10f} {:.10f}".format(x, y))
```第一个深度优先搜索计算子树大小。 为顶点存储的值包括顶点本身，因此子树大小的总和正是必须分布在当前节点下方的结构量。 

第二次遍历执行几何构造。 变量`direction`是进入当前顶点的边所使用的方向。 孩子们被放置在周围`direction + pi`，它指向远离父级的方向。 变量`width`是当前子树可用的角度空间。 

子间隔是使用浮点比率计算的。 顶点总数只有 1000 个，因此普通双精度足以满足所需的误差范围。 坐标仍然很小，因为每个级别仅移动一个单位，并且最大深度为 1000。 

# 工作示例

 对于第一个样本，根有四个子节点。 因为每个子子树的大小都是一，所以整个圆被分成四个相等的部分。 

| 顶点| 家长 | 指定方向 | 职位|
 | --- | --- | --- | --- |
 | 1 | 无 | 0 | (0,0) | (0,0) |
 | 2 | 1 | 0 | (1,0)|
 | 3 | 1 | π/2 | (0,1)|
 | 4 | 1 | π| (-1,0) | (-1,0) |
 | 5 | 1 | 3π/2| (0,-1) | (0,-1) |

 确切的坐标与示例输出不同，但都满足所需的几何形状。 痕迹表明该算法只需要有效的绘图，而不是特定的绘图。 

对于第二个样本，顶点 2 有两个子节点，而顶点 1 有一个子节点和一个叶子节点。 

| 顶点| 行动| 原因 |
 | --- | --- | --- |
 | 1 | 原产地 | 建筑根源|
 | 2 | 远离一个单位 | 根在一个方向上的唯一子节点 |
 | 3 | 放置在 root 的剩余区域 | 保持分支分开 |
 | 4 | 分割顶点 2 的区域 | 顶点 2 的第一个子节点 |
 | 5 | 分割顶点 2 的区域 | 顶点 2 的第二个子节点 |

 该示例的重要部分是子树可以从非根顶点继续生长，同时仍然保留在分配给它的角度区域内。

 # 边缘情况

 对于两个顶点树：```
2
1 2
```根有一个孩子。 该算法为该子级提供整个可用的角度间隔，并将其放置在恰好一个单位之外。 没有兄弟子树，因此不可能交叉。 

对于星树：```
5
1 2
1 3
1 4
1 5
```根将整个圆分成四个孩子。 由于每个子树都具有相同的大小，因此所有子树都接收相同的角度区域。 它们的片段以不同的方向离开中心，递归调用立即停止。 

对于链条：```
4
1 2
2 3
3 4
```除叶子之外，每个顶点只有一个子节点。 整个间隔会重复向下传递，但每个下一个顶点仍然沿当前方向精确放置一个单位。 不存在分支，因此不存在可能的交集。
