 ## 解决方案
 ## 问题理解

 任务是从加密字符串中恢复原始日记文本。 该密码使用自动密钥机制：第一个`n`密钥的字符未知，但此后密钥会重复明文开头的字符。 玛丽知道最后一个`n`明文的字符，也有完整的密文。 使用这些信息，我们必须重建整个明文。 

加密适用于转换为从 0 到 25 的数字的字母。对于每个位置，密文值是明文值与密钥值模 26 之和。`n`关键字符是隐藏关键字，而其余关键字符是从较早的明文位置复制的。 输出是按原始顺序排列的明文字符串。 

文本长度最多为 100 个字符，已知后缀长度最多为 30 个。这些小界限允许多种可能的方法，但密码的结构给出了直接线性解决方案。 即使限制大得多，解决方案也接近`O(m)`仍然是自然目标，因为必须确定明文的每个字符。 

棘手的部分是已知的明文字符位于消息的末尾，而未知的密钥前缀则影响开头。 粗心的方法可能会尝试从左到右解密，但第一个`n`职位没有已知的关键值。 另一个常见的错误是忘记已知后缀准确地给出了恢复未知密钥所需的缺失明文值。 

例如，与：```
1 3
a
bac
```正确的输出是：```
aaa
```最后一个明文字符称为`a`。 最后一个关键字符是第一个明文字符，因此最后一个密文字符给出了等式`c = a + a`，它确定第一个明文字符。 假设密钥前缀是已知字符的方法将会失败，因为已知字符是明文，而不是密钥。 

当已知后缀长度几乎是整个字符串时，会出现另一种边缘情况：```
2 3
ab
bbc
```正确的输出是：```
abc
```前面只有一个未知字符，算法仍然必须使用最后一个字符与较早明文位置之间的关系。 仅当许多字符未知时才有效的解决方案可能会在此处产生不正确的索引。 

## 方法

 直接的暴力方法将尝试每个可能的长度秘密关键字`n`。 每个关键词都有`26^n`对于每一种可能性，我们都可以生成密钥，解密密文，并检查生成的明文是否以已知后缀结尾。 这种方法是正确的，因为真正的关键字可以保证在测试的候选关键字中。 然而，即使是很小的值也是不可能的`n`。 和`n = 30`，候选人的数量是`26^30`，这远远超出了可以处理的范围。 

不需要暴力破解的原因是已知后缀修复了依赖于明文的密钥部分。 对于第一个之后的位置`n`，关键字符正是位于的明文字符`n`职位较早。 最后一个`n`明文字符是已知的，所以我们可以使用最后一个`n`先恢复未知的密文字符`n`关键人物。 

一旦知道隐藏密钥前缀，就可以解密整个消息。 重要的观察是后缀不仅仅是一个验证条件。 它提供了反转自动键关系所需的缺失信息。 

暴力破解之所以有效，是因为考虑了所有可能的密钥，但由于搜索空间呈指数级增长，所以会失败。 观察到已知的明文后缀揭示了密钥前缀，从而将问题简化为对字符串进行几次线性传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(26^n * m) | O(26^n * m) | O(米) | 太慢了 |
 | 最佳 | O(米) | O(米) | 已接受 |

 ## 算法演练

 1. 存储密文和已知的最终结果`n`明文字符。 已知后缀代表答案的结尾，将用于恢复未知密钥前缀。 
2.恢复第一个`n`使用最后的关键人物`n`密文位置。 对于位置处的密文字符`i`，对应的明文字符是已知的，因为它在后缀中。 等式是`cipher[i] = plain[i] + key[i] (mod 26)`，因此关键字符可以计算为`key[i] = cipher[i] - plain[i] (mod 26)`。 

这是有效的，因为最后`n`位置是明文和密文都可用的唯一位置。 
3. 构建完整密钥。 第一个`n`字符是恢复的秘密前缀。 后面的每个关键字符都是从明文字符复制而来`n`职位较早。 
4. 使用生成的密钥解密完整的密文。 对于每个位置，用密文值模 26 减去密钥值即可获得明文值。 
5. 输出重构后的明文。 

该算法背后的不变性是每个生成的密钥字符都与密码的密钥定义相匹配。 第一个`n`从已知明文的位置恢复字符，并且从已经重建的明文复制每个后面的字符。 由于密钥在每个位置都是正确的，因此应用逆加密公式会产生唯一可能的明文。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    suffix = input().strip()
    cipher = input().strip()

    key = [''] * m
    plain = [''] * m

    for i in range(n):
        plain[m - n + i] = suffix[i]

    for i in range(n):
        pos = m - n + i
        key[pos] = chr((ord(cipher[pos]) - ord(plain[pos])) % 26 + ord('a'))

    for i in range(n):
        key[i] = key[m - n + i]

    for i in range(n, m):
        key[i] = plain[i - n]

    for i in range(m):
        plain[i] = chr((ord(cipher[i]) - ord(key[i])) % 26 + ord('a'))

    print(''.join(plain))

if __name__ == "__main__":
    solve()
```该解决方案首先为明文和密钥创建数组，以便可以独立填充位置。 已知后缀直接放入明文数组的末尾。 

恢复密钥的循环使用最后一个`n`职位。 该表达式使用模 26，因为字母表中的减法可以回绕，例如恢复`z`从负的中间值。 

恢复键前缀后，将其复制到键数组的开头。 后面的关键位置由明文位置填充`n`较早的地方。 顺序很重要，因为密钥取决于明文，并且在使用这些明文字符之前必须知道它们。 

最后一个循环执行逆密码操作。 Python 整数不会溢出，因此模计算仅处理字母表换行。

 ## 边缘情况

 第一个边缘情况是当`n = 1`。 在输入中：```
1 3
a
bac
```最终的明文字符是已知的。 该算法放置`a`在最后一个位置，从最后一个密文字符计算唯一的密钥前缀字符，然后解密剩余的位置。 它输出：```
aaa
```将已知字母而不是明文视为密钥的解决方案在这里会失败，因为两者在密码中具有不同的角色。 

第二种边缘情况是当已知后缀几乎是整个消息时：```
2 3
ab
bbc
```该算法首先存储`ab`作为最后两个明文字符。 它使用这两个字符和最后两个密文字符来恢复隐藏的密钥前缀，然后解密第一个字符。 结果是：```
abc
```这证实了该解决方案可以处理只需要发现一小部分明文的情况。 

重复字符的情况：```
3 6
aaa
aaaaaa
```还需要正确的模减法。 每个关键人物都是`a`，并且每个明文字符都保留`a`。 该算法执行相同的计算而不依赖于字符差异，产生：```
aaaaaa
```
