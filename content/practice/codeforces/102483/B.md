 ## 解决方案
 ## 问题理解

 我们有一个谈判主题的有向无环图。 每个主题都有一个基本讨论时间`e[i]`，并且某些主题只能在某些其他主题完成后才能讨论。 有效的调度是该图的任何拓扑排序。 

如果主题放置在位置`p`在日程安排中，第一次会议占据了位置`0`，会议需要`e[i] + p`分钟。 额外的`p`会议纪要来自对之前所有会议的回顾。 目标是选择有效的顺序，最大限度地缩短单次会议的最长持续时间。 

输入给出主题的数量，然后给出每个主题的基本时间和必备主题的列表。 输出是最大值的最小可能值`e[i] + p`所有有效的时间表。 

的约束条件为`n`最多`400000`排除重复尝试不同顺序或对子集使用动态规划的算法。 该图最多可以有`400000`依赖边缘，因此预期的解决方案必须接近线性时间。 具有优先级队列的普通拓扑排序是合适的，因为它仅处理每个主题和边缘对数次。 

有少数情况很容易处理不当。 当多个主题没有依赖关系时，必须首先调度最大的基准时间。 例如：```
3
10 0
1 0
1 0
```答案是`12`。 最佳顺序是主题与时间`10`首先，给出长度`10`,`2`， 和`3`。 首先选择较小的主题会给大主题带来不必要的延迟。 

第二种情况是长主题最初不可用：```
2
1 1 2
100 0
```答案是`101`。 第二个主题必须首先发生，因为第一个主题取决于它。 贪婪的实现，忽略依赖关系并简单地排序`e`将产生无效的时间表。 

最后一个极端案例是一个主题：```
1
500 0
```答案是`500`。 没有回顾时间，因为不存在更早的会议。 

## 方法

 直接的方法是在重复搜索所有当前可用主题的同时尝试构建时间表。 在每个位置，我们可以扫描每个主题，检查它是否可用，然后选择最大的主题`e`。 这是正确的，因为每个点的最佳选择都是最容易被延迟的主题。 然而，随着`400000`主题，扫描每个位置的所有主题大约需要`400000^2`， 或者`1.6 * 10^11`，检查最坏的情况，这太慢了。 

有用的观察是，选择下一个主题时所需的唯一信息是先决条件已完成的主题集。 这正是卡恩的拓扑排序算法所维持的状态。 我们不是扫描所有主题，而是将可用主题保留在按以下顺序排列的最大堆中`e`。 每当主题变得可用时，它就会被插入到堆中。 下一次会议始终是基本持续时间最长的可用主题。 

这种贪婪的选择起作用的原因是，将主题延迟一个位置会使会议长度恰好增加一分钟。 如果当前有两个可用主题`a`和`b`， 和`e[a] > e[b]`, 放置`b`前`a`增加较大主题的最终持续时间，但不会帮助任何依赖关系。 交换它们只能提高或保持最大会议长度。 重复这个交换参数意味着最优调度总是可以转化为选择最大可用调度的调度`e`步步。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳 | O((n + m) log n) | O((n + m) log n) | O(n + m) | 已接受 |

 ## 算法演练

 1. 构建依赖图。 对于每个先决关系`a -> b`， 店铺`b`作为一个主题，在之后变得更接近可用`a`已完成。 还存储每个主题未完成先决条件的数量。 
2. 将每个具有零个未完成先决条件的主题放入按其基本时间排序的最大堆中。 这些话题是唯一可以合法首先讨论的话题。 
3. 反复从堆中移除基时间最大的主题。 它当前的位置是已经完成的会议数量，因此将答案更新为`e[i] + position`。 
4. 完成一个主题后，根据该主题减少每个主题的先决条件数量。 如果其中一个计数变为零，则将该主题插入堆中，因为它现在可用。 
5. 继续，直到每个主题都安排完毕。 存储的最大值是可能的最小最长会议。 

为什么它有效：在每个点，堆都准确地包含接下来可以合法选择的主题。 在这些选择中，选择最大的`e`值是最优的，因为任何可用主题都可以与所选主题进行交换，而不会违反依赖关系，并且不会移动更大的主题`e`后面的话题只能增加最大值。 由于每个决策都可以通过此交换论证来证明合理，因此整个排序是最优的。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n = int(input())
    e = [0] * n
    graph = [[] for _ in range(n)]
    indeg = [0] * n

    for i in range(n):
        data = list(map(int, input().split()))
        e[i] = data[0]
        d = data[1]
        indeg[i] = d
        for x in data[2:]:
            graph[x - 1].append(i)

    heap = []
    for i in range(n):
        if indeg[i] == 0:
            heapq.heappush(heap, (-e[i], i))

    ans = 0
    done = 0

    while heap:
        neg_e, u = heapq.heappop(heap)
        ans = max(ans, -neg_e + done)
        done += 1

        for v in graph[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                heapq.heappush(heap, (-e[v], v))

    print(ans)

if __name__ == "__main__":
    solve()
```该图存储从先决条件到依赖主题的传出边。 这个方向使得完成主题后的更新变得简单，因为我们只需要访问可能可用的主题。 

该堆是作为 Python 标准库中的最小堆实现的，因此存储的值为`-e[i]`模拟最大堆。 变量`done`是计划中当前从零开始的位置。 这个位置的会议时间很长`e[i] + done`。 

所有持续时间都适合 Python 整数。 最大可能的答案如下`1,400,000`，但 Python 的任意精度也消除了任何溢出问题。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O((n + m) log n) | O((n + m) log n) | 每个主题进入和离开堆一次，并且每个依赖边都被处理一次。 |

 ## 边缘情况

 对于独立主题的情况：```
3
5 0
1 0
2 0
```所有主题立即进入堆。 该算法选择`5`， 然后`2`， 然后`1`，产生会议长度`5`,`3`， 和`3`。 答案是`5`，而较小的第一排序会不必要地增加最大值。 

对于强制依赖情况：```
2
1 1 2
100 0
```最初只有主题 2 可用，因此堆中没有选择。 主题 2 完成后，主题 1 就可用。 该算法计算`100 + 0`和`1 + 1`, 给予`101`。 

对于相等的值：```
3
10 0
10 0
10 0
```堆可能会首先返回三个主题中的任何一个，因为它们的优先级相同。 每个可能的顺序都会给出相同的结果，最终主题有两分钟的回顾时间，产生`12`。
