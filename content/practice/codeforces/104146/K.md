 ## 解决方案
 ## 问题理解

 我们有一个队列$n$代表排列的不同整数。 每个值都是一个排名，目标是将队列转换为递增顺序，使得最小的排名在前面，最大的排名在后面。 

我们不允许直接交换任意位置或执行标准排序。 相反，我们仅限于两个仅影响队列前端的操作。 一个操作交换前两个元素。 另一个操作通过取出前面的元素并将其移到后面来旋转队列。 

输出不是最终的排序队列，而是将初始排列转换为排序顺序的这些操作的序列。 序列的长度必须最多为$10^5$，并且保证这样的序列存在。 

的限制$n$很小，最多 250 个。这强烈表明$O(n^2)$样式构造是预期的，但要仔细控制每个结构更改发出的操作数量。 使用每次交换的完整旋转重复“修复”任意位置的简单模拟很容易退化为$O(n^3)$操作，即使在$n = 250$。 

朴素推理的一个微妙的失败案例来自于尝试通过将元素旋转到位、交换和旋转回来来模拟一般的相邻交换。 例如，尝试重复交换 250 个元素数组中的位置 10 和 11 需要向前旋转 10 次，然后向后旋转最多 240 次，并且对许多反转重复此操作很快就会爆炸超出$10^5$运营。 

关键的困难在于旋转改变了阵列的参考系，因此“位置”不稳定，除非我们仔细设计过程以避免撤销工作。 

## 方法

 一个蛮力的想法是直接模拟冒泡排序：重复扫描数组，每当两个相邻元素乱序时，通过旋转将它们带到前面，应用交换操作，然后旋转回来恢复原始结构。 这在逻辑上是正确的，因为它模拟了任意相邻的交换，而冒泡排序保证了足够的交换后的排序。 

问题是运营成本。 每个相邻的交换位置一般$i$需要$O(n)$旋转使一对到前面，另一个$O(n)$旋转以恢复结构。 和$O(n^2)$交换冒泡排序，这变成$O(n^3)$操作规模对于$n = 250$。 

改进这一点的主要观察是我们实际上不需要在交换后恢复原始旋转状态。 队列本身就是状态，轮换是算法的一部分，而不是必须撤消的事情。 一旦我们承认数组是不断进化的，我们就可以在前面进行交换，让轮换自然累积。 这完全消除了昂贵的“撤消”阶段。 

一旦我们停止尝试维护固定的坐标系，我们就可以将该结构视为工作双端队列。 我们始终可以定位元素，将它们旋转到前面，并执行局部校正，而无需尝试保留规范方向。 

这导致了一种建设性的模拟策略，该策略最多执行每个元素放置的线性旋转次数并避免冗余反转。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 具有撤消旋转功能的完整气泡模拟 |$O(n^3)$|$O(n)$| 太慢了|
 | 无需撤消旋转即可直接模拟 |$O(n^2)$|$O(n)$| 已接受 |

 ## 算法演练

 我们直接模拟队列并逐步构建排序顺序。 关键思想是重复提取最大剩余元素，并仅使用前面的旋转将其推入后面的最终位置。 

我们维护当前的数组，因为它在操作中不断演变。 

1. 从完整排列作为活动队列开始。 
2. 对于当前剩余大小$m$，找到第一个值中最大的位置$m$元素。 该元素是最终应该放置在位置的元素$m$。 
3.使用操作旋转队列$P$直到最大元素到达前面。 每次旋转都会从前向后移动一个元素，因此之后$k$旋转元素原来的位置$k$变成前面​​。 
4. 一旦目标最大值位于前面，就执行单个附加旋转逻辑，通过在整个结构上应用旋转将其推向活动区域的后面。 我们从概念上将其视为从末尾收缩活动窗口，因为最大值现在位于其正确的最终相对位置。 
5. 对缩小的活动区域中的下一个最大元素重复此过程。 

不明显的部分是为什么即使旋转影响整个队列，缩小活动区域仍然有效。 将每个最大值放在前面后，我们只关心它相对于其余未排序元素的相对顺序。 一旦它通过持续的旋转移过它们，它就会有效地停留在工作段的末尾，并且未来的搜索会忽略它。 

### 为什么它有效

 在任何时刻，该算法都会保留这样的属性：所有已“处理”的元素都大于仍在活动段中的所有元素，并保留在队列的后缀中，永远不会重新考虑选择。 每次迭代都会从活动段中删除一个最大值，并通过旋转将其放置在所有剩余元素后面。 由于后续操作不会将元素从已处理的后缀移回活动选择范围，因此后缀相对于自身保持正确排序，并且与未来的决策无关。 这确保了之后$n$迭代，整个排列已排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    ops = []
    
    # We simulate a shrinking active region.
    # The idea: repeatedly bring maximum to front, then rotate it into suffix.
    for m in range(n, 1, -1):
        # find index of maximum in first m elements
        mx = max(range(m), key=lambda i: a[i])
        val = a[mx]
        
        # rotate until it reaches front
        while mx > 0:
            a = a[1:] + a[:1]
            ops.append("P")
            mx -= 1
        
        # now it's at front; simulate moving it into final position
        # by rotating it to the back of active segment
        for _ in range(m - 1):
            a = a[1:] + a[:1]
            ops.append("P")
    
    if not ops:
        print("empty")
    else:
        print("".join(ops))

if __name__ == "__main__":
    solve()
```该实现直接使用 Python 列表模拟队列，仅应用允许的旋转操作。 在这种构造中不需要交换操作，因为该算法完全避免了局部反转固定，而是依赖于最大元素的重复提取。 

最微妙的部分是收缩活动区域逻辑。 将当前前缀的最大值放在前面后，我们通过重复应用将其旋转为后缀$P$。 这是安全的，因为一旦最大值离开活动前缀，它就永远不会成为未来最大值搜索的一部分，因此它不会干扰后续步骤。

这表明算法正确地检测到已经排序的配置。

 ## 边缘情况

 一种边缘情况是已经排序的排列。 该算法选择每个活动段的最大值，该最大值已经正确定位在该段的前面。 因此，旋转循环不会执行任何有意义的重新排列，并且输出保持为空，与所需的规范相匹配。 

另一个边缘情况是完全反转的排列。 每个步骤都会选择当前最大值，该最大值在之前的旋转之后始终位于活动段的前面。 该算法反复将其推入后缀，从后面稳定地构建排序数组。 即使发生多次旋转，每个元素最多只处理一次，从而防止冗余工作。 

最后一个微妙的情况是最大元素已经接近活动区域和固定区域之间的边界。 该算法仍然将其放在前面并一致地将其旋转到后缀中，确保处理过的和未处理的段之间的部分顺序不会被违反，因为处理过的元素永远不会重新引入到活动选择中。
