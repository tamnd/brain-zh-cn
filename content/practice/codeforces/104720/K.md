 ## 解决方案
 ## 问题理解

 我们有几个“甜甜圈”，每个甜甜圈由两个半径描述。 内半径定义了一个孔，外半径定义了甜甜圈的整个范围。 如果一个甜甜圈的外边界完全适合另一个甜甜圈的孔，则可以将其放置在另一个甜甜圈的孔内。 这种嵌套可以继续，形成一条链，其中每个下一个甜甜圈都适合前一个甜甜圈的孔。 

有效的“甜甜圈环”就是这样一串嵌套的甜甜圈。 如果我们采用一条链，则总贡献仅取决于半径：每个甜甜圈贡献其面积，而最外层结构的孔将面积作为空白空间移除。 简化几何形状后，目标减少为最大化数量，该数量线性取决于有效嵌套顺序中所选甜甜圈的平方半径。 

具体来说，对于每个甜甜圈，对最终值的贡献可以表示为$R_i^2 - r_i^2$，而嵌套引入了约束：如果甜甜圈 A 在甜甜圈 B 内，则$R_A \le r_B$。 目标是选择一条链，使从这些值得出的全局得分最大化，同时尊重嵌套约束。 

输入尺寸$n \le 10^5$意味着任何解决方案都比$O(n \log n)$存在超时风险。 检查所有对或所有链的二次解决方案立即不可行，因为它需要最多$10^{10}$运营。 

一些微妙的边缘情况很重要：

 必须正确处理单个甜甜圈。 如果这是唯一的选择，答案很简单$R^2 - r^2$，可以为负数。 例如，一个甜甜圈$r = 5, R = 10$贡献$100 - 25 = 75$。 

另一个边缘情况是所有甜甜圈对于嵌套都“不兼容”，这意味着没有两个甜甜圈满足$R_i \le r_j$。 那么答案就是最大单个值，而不是零或空链。 例如，$(r,R) = (1,10), (2,3)$给出最佳答案$\max(100-1, 9-4)$。 

第三种情况是，当许多甜甜圈共享相同或接近相同的半径时，这可能会打破假设严格排序而不仔细处理相等性的天真贪婪方法。 

## 方法

 暴力解决方案将尝试构建每个可能的嵌套链。 对于每个甜甜圈，我们可以尝试将其作为起点，并递归地附加其外半径适合当前内半径的任何甜甜圈。 这形成了一个可能性的 DAG，其中每个节点都可以分支到许多其他节点。 在最坏的情况下，每个甜甜圈都可以融入许多其他甜甜圈，从而导致探索链呈指数级增长。 即使修剪也没有多大帮助，因为有效链的数量仍然可能非常大。 

关键的观察结果是，嵌套施加了严格的排序条件：如果甜甜圈 A 进入甜甜圈 B 内部，则$R_A \le r_B$。 这将问题转换为按半径排序的有向非循环结构，其中过渡仅从较小的外半径到较大的内半径。 一旦我们按照有意义的键对甜甜圈进行排序，我们就可以将问题转化为针对有效前辈的一维优化。 

我们将每个甜甜圈重新解释为段约束和值。 任务变成选择一个序列，其中每个下一个元素满足单调可行性条件并贡献一个值。 这是在排序端点上进行动态编程的经典设置，对于每个甜甜圈，我们使用所有兼容的先前甜甜圈来计算以其结尾的最佳链。 

过渡取决于找到其外半径适合当前内半径的先前最佳甜甜圈。 按内半径排序允许我们在外半径的压缩坐标上使用二分搜索或芬威克树。 这减少了从线性扫描到对数查询的兼容性检查。 

因此，我们不是枚举链，而是按递增顺序处理甜甜圈，并维护一个存储给定外半径阈值的最佳可实现值的结构。

 ## 算法演练

 我们将每个甜甜圈转换为一对坐标：约束端点和值。 

## 步骤 1：标准化表示

 对于每个甜甜圈，计算其贡献值$v_i = R_i^2 - r_i^2$。 我们还保留其兼容性边界：它只能跟随外半径最大为 的甜甜圈$r_i$。 

这使得每个甜甜圈同时成为“状态”和“约束”。 

## 步骤 2：按约束排序

 通过增加内半径对甜甜圈进行排序$r_i$。 这确保了在处理甜甜圈时，所有潜在的前体（具有更小或相等的外半径要求）都已被考虑。 

这样做的原因是可行性仅取决于比较一个外半径与另一个内半径，因此按内半径排序会创建自然的处理顺序。 

## 步骤 3：外半径上的坐标压缩

 收集全部$R_i$值并压缩它们。 这允许我们在 Fenwick 树或线段树中对它们进行索引。 

压缩是必要的，因为$R_i$可以达到$10^9$，使得直接索引变得不可能。 

## 步骤4：动态规划结构

 维持结构`best[x]`表示有效链的最大可实现的美感，其最后一个甜甜圈的外半径至多为压缩坐标$x$。 

这将兼容性转变为前缀最大查询。 

## 步骤 5：按排序顺序处理甜甜圈

 对于每个甜甜圈$i$，我们查询可以在它之前的最佳链。 因为它必须满足$R_{prev} \le r_i$，我们查询外半径达到的所有状态$r_i$。 

然后我们计算：$$dp_i = v_i + \max(dp \text{ among valid predecessors})$$我们还考虑仅用这个甜甜圈开始一个新的连锁店。 

计算后$dp_i$，我们更新对应位置的结构$R_i$。 

## 第 6 步：最终答案

 答案是所有值中的最大值$dp_i$。 

### 为什么它有效

 关键的不变量是在处理完索引处的所有甜甜圈之后$i$，该结构仅使用有效的早期甜甜圈来存储每个可行外半径边界的最佳可能链值。 由于处理顺序遵循内半径的增加，因此保证已包含每个有效的前驱。 由于过渡保留了可行性，并且我们总是采用最好的前任，因此不会错过任何最佳链。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [-10**30] * (n + 1)

    def update(self, i, v):
        while i <= self.n:
            if v > self.bit[i]:
                self.bit[i] = v
            i += i & -i

    def query(self, i):
        res = -10**30
        while i > 0:
            if self.bit[i] > res:
                res = self.bit[i]
            i -= i & -i
        return res

def main():
    n = int(input())
    donuts = []
    Rs = []

    for _ in range(n):
        r, R = map(int, input().split())
        donuts.append((r, R))
        Rs.append(R)

    Rs_sorted = sorted(set(Rs))
    comp = {v: i + 1 for i, v in enumerate(Rs_sorted)}

    donuts.sort()

    fw = Fenwick(len(Rs_sorted))

    ans = -10**30

    for r, R in donuts:
        v = R * R - r * r
        # best chain ending with R_i <= r
        # need all previous with outer radius <= r
        # find index of r in compressed Rs
        # upper bound
        import bisect
        idx = bisect.bisect_right(Rs_sorted, r)
        best_prev = fw.query(idx)

        if best_prev < 0:
            best_prev = 0

        cur = best_prev + v
        ans = max(ans, cur)

        fw.update(comp[R], cur)

    print(ans)

if __name__ == "__main__":
    main()
```该解决方案依赖于在压缩外半径上维持前缀最大值。 Fenwick 树仅用于最大查询，因此更新存储最大值而不是总和。 微妙之处在于通过排序将可行性转换为前缀条件，然后使用二分查找将内半径约束与压缩坐标系对齐。 

一个容易犯的错误是忘记链可以从任何甜甜圈开始，因此前驱值必须允许为零。 这是通过在扩展之前将负结果钳位为零来处理的。
