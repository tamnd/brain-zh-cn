 ## 解决方案
 ## 问题理解

 我们得到一系列汉堡，每个汉堡从左到右排成一行，每个汉堡都有一个风味值。 对于每个职位`i`，我们需要计算有多少个较早的位置`j`可以搭配`i`在非常具体的条件下。 

有效的`j`必须在左侧`i`且风味值较小。 除此之外，`j`在单调意义上也必须是“可见的”：在`j`和`i`，不能有任何元素大于`f_j`。 同样地，一旦我们选择了一位候选人`j`，如果我们从`j`向右，我们第一次看到一个值严格大于`f_j`，这会阻止其对超出其范围的所有内容的可见性。 

所以对于每一个`i`，我们正在计算在删除在其本地区域中占主导地位的所有早期元素后仍然相关的早期较小元素。 

约束条件`N ≤ 10^5`意味着任何解本质上都是二次的，围绕`N^2`，太慢了。 对每对进行粗暴比较需要大约`10^10`最坏情况下的检查，一秒钟都不可行。 这立即将我们推向线性或近线性结构，最有可能使用堆栈或单调维护。 

当值相等时，会出现微妙的边缘情况。 由于条件要求严格较小`f_j < f_i`，相等的值永远不会起作用，但它们仍然可以阻止可见性，具体取决于结构的维护方式。 当数组严格递减时，会出现另一个极端情况，其中每个元素对所有先前元素都是可见的，从而最大化计数，而不是严格递增，其中每个答案都为零。 

## 方法

 一种直接的方法是检查每一对`(j, i)`和`j < i`，检查是否`f_j < f_i`，然后扫描区间`(j, i)`确保没有元素超过`f_j`。 根据定义，这是正确的，但第三个条件引入了额外的扫描，将每对检查变成线性工作。 在最坏的解释中，完整的复杂性变成三次方，或者在预处理中最多变成二次方，这远远超出了限制。 

关键的观察结果是“之间不存在阻塞元素”`j`和`i`大于`f_j`” 定义了对先前元素的支配结构。每个元素仅保持“活动”状态，直到被后来的更大值所掩盖。这正是单调堆栈的行为：元素形成递减结构，任何新元素都会删除无法再充当有效锚点的较弱候选元素。

 一旦我们维护了一堆候选索引，其中它们的值正在减少，每个新元素只能与一小部分先前的“幸存”元素交互。 对于每个位置`i`，有效的`j`值正是那些小于的堆栈元素`f_i`，因为任何更大或相等的都是无关紧要的，并且之前删除的任何内容都由于被中间的某些内容阻挡而无法做出贡献。 

因此，我们可以从左到右处理，保持风味值的单调递减堆栈。 对于每个`i`，我们从堆栈中删除所有严格小于的元素`f_i`， 因为`i`现在阻止他们将来在同一角色中的可见性。 剩余的堆栈结构代表有效的贡献者，我们计算其中有多少人满足条件。 

这将问题转化为具有摊销常量堆栈操作的单遍问题。

 ## 算法演练

 我们维护一个堆栈，用于存储以前汉堡的索引，并进行排列，以便它们的风味值形成递减序列。 

1.初始化一个空栈和一个数组`ans`尺寸的`N`。 
2. 迭代每个索引`i`从左到右。 
3. 当栈不为空且栈顶的风味小于`f[i]`，弹出它。 这些元素不再相关，因为它们主要由`i`。 
4.出栈后，栈中只包含flavor大于等于的元素`f[i]`，这意味着他们阻止了他们背后的任何较弱的元素进一步做出贡献。 
5.当前位置的答案`i`是堆栈中仍然满足的剩余元素的数量`f_j < f_i`。 在此结构中，这些元素与步骤 3 中删除的元素完全对应，这些元素仍然是可见的候选者`i`。 
6. 记录计算出的计数`i`。 
7. 推送索引`i`作为未来职位的新潜在候选人加入堆栈。 

关键是每个元素最多进入和离开堆栈一次，因此总工作量是线性的。 

### 为什么它有效

 在任何时候，堆栈都会维护一个结构，其中每个元素都代表某个未来元素的潜在“最后阻止者”。 当有新值时`f[i]`到达时，它会删除所有较小的值，因为它们再也不能充当有意义的边界：任何使用它们的未来元素将受到`i`第一的。 这保留了堆栈始终是按递减值排序的有用前辈的最小集合的不变性，确保对它进行计数准确地捕获有效的前辈。`j`每个值`i`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    f = list(map(int, input().split()))
    
    stack = []
    ans = [0] * n
    
    for i in range(n):
        # pop all strictly smaller values
        while stack and f[stack[-1]] < f[i]:
            stack.pop()
        
        # remaining stack elements are >= f[i], they do not count as valid j
        # valid j are exactly those removed in this step, but we don't need to
        # explicitly count them via another structure because the structure
        # ensures each element contributes exactly once when it gets popped
        ans[i] = 0  # will be adjusted conceptually via contributions below
        
        stack.append(i)
    
    # second pass idea correction: we instead compute contributions directly
    stack = []
    ans = [0] * n
    
    for i in range(n):
        count = 0
        while stack and f[stack[-1]] < f[i]:
            stack.pop()
            count += 1
        
        ans[i] = count
        stack.append(i)
    
    sys.stdout.write("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```该解决方案在代码中概念性地处理数组两次，但只有第二次循环才是真正正确的计数机制。 对于每个`i`，我们弹出所有更早的严格较小的元素，并且每个弹出对应一个有效的`j`为了这`i`。 这些弹出的元素正是那些成为“可见端点”的元素`i`因为它们之间不存在中间较大的元素`i`，由单调堆栈结构强制执行。 

关键的微妙之处在于堆栈确保我们只考虑未被任何早期较大值阻塞的元素。 因此，每次弹出时，我们都会同时确认两个条件：从左到右的顺序和可见性约束。

 ## 边缘情况

 单元素输入，例如`[7]`结果是一个空堆栈，所以答案是`0`，然后该元素被推入。 该算法无需特殊外壳即可处理此问题。 

在严格递减序列中，例如`[5,4,3,2,1]`，没有元素会触发弹出，因为没有任何元素小于当前值，因此每个答案都保持为零。 堆栈只是增长，反映出没有更早的元素成为有效的`j`以便以后获得更大的值。 

在严格递增的序列中，例如`[1,2,3,4]`，每个新元素恰好弹出一个前任元素，从而给出一个链，其中每个位置恰好贡献一对有效的元素。 当出现较大值时，堆栈确保每个元素恰好被删除一次，与预期的计数线性累积相匹配。
