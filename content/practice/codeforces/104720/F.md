 ## 解决方案
 ## 问题理解

 我们对厨师进行了圆形排列，每个厨师都与代表其“味蕾指数”的固定值相关联。 我们选择一位起始厨师，然后按顺序遍历圆圈，以顺时针方向循环访问每个厨师一次。 不同的是，访问的顺序很重要：第一个访问的厨师贡献的价值乘以 1，第二个厨师贡献的价值乘以 2，依此类推，直到第 n 个厨师的贡献值乘以 n。 

任务是计算每个可能的起始位置的加权和并返回最大可能值。 

输入规模可达 100,000 个厨师。 任何尝试所有旋转并从头开始重新计算完整加权和的解决方案都需要 O(n^2) 操作，这太慢了。 我们需要一种更接近线性时间的方法。 

关键的边缘情况是所有值都相等。 在这种情况下，每次旋转都会产生相同的结果，并且正确的解决方案不得由于旋转索引错误而意外地错误地重新计算。 另一个微妙的情况是当存在一个非常大的值时； 它相对于较高乘数（后面的位置）的位置决定了答案，因此旋转处理必须精确。 

## 方法

 天真的想法很简单。 对于每个起始位置 k，我们模拟绕圈行走，累加 i 乘以第 i 个访问元素的总和，并跟踪最佳结果。 每次模拟的成本为 O(n)，并且有 n 个起点，总复杂度为 O(n^2)。 当 n 达到 100,000 时，这会导致大约 10^10 次操作，这是不可行的。 

表达式的结构暗示了更有效的观点。 如果我们固定一个旋转，则加权和是按该旋转顺序排列的数组的线性函数。 将起点移动一步并不会从头开始重建序列； 它只会将每个元素的权重位置移动一位。 这意味着我们可以逐步更新答案，而不是重新计算它。 

令当前排列为固定起始轮换中的 A[0]、A[1]、...、A[n-1]。 假设我们已经知道这种排列的加权和。 当我们将数组旋转一步时，最后一个元素会移到前面，而其他每个元素都会右移一个位置。 这种转变在加权和的连续值之间创建了清晰的代数关系，允许旋转之间的 O(1) 转换。 

这将问题转化为计算一个初始加权和，然后使用从旋转效应导出的递推式将其更新 n 次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算所有元素的总和。 该值将在旋转之间的转换中重复使用。 
2. 假设数组从索引 0 开始，计算初始加权和，其中位置 i 贡献 (i+1) * A[i]。 这给出了基线配置。 
3. 对于每次旋转，从前一个旋转导出下一个加权和。 当数组向右旋转一个位置时，除了移动到前面的元素（从权重 n 到权重 1）之外，每个元素的权重都会增加 1。这种不平衡会产生确定性调整。 
4. 使用递推式：如果当前加权和为 S，总和为 T，数组大小为 n，则旋转一次后新和变为 S' = S + T - n * A[n - 1 - k]（取决于旋转方向）。 在实现中，我们维护滑动窗口解释以避免索引混乱。 
5. 迭代所有 n 次旋转，更新结果并跟踪看到的最大值。 

### 为什么它有效

每次旋转都会以结构化的方式排列索引：除了环绕的元素之外，每个元素的贡献均按总和均匀增加。 这使得加权和的变化仅取决于总和和一个边界元素。 由于此更新规则对于每个旋转步骤都是精确的，因此不需要重新计算各个位置，并且该算法仅探索每个有效起始位置一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n_and_rest = input().strip().split()
    if not n_and_rest:
        return
    n = int(n_and_rest[0])
    
    if len(n_and_rest) == n + 1:
        arr = list(map(int, n_and_rest[1:]))
    else:
        arr = list(map(int, input().split()))
    
    n = len(arr)

    total = sum(arr)

    cur = 0
    for i in range(n):
        cur += (i + 1) * arr[i]

    best = cur

    for i in range(1, n):
        cur = cur + total - n * arr[n - i]
        if cur > best:
            best = cur

    print(best)

if __name__ == "__main__":
    solve()
```该代码首先读取数组并计算其总和。 然后，它直接使用问题的定义来计算初始加权和。 

关键的递归出现在循环中：每次迭代都模拟将起点在圆形数组中向前移动一个位置。 期限`total`解释了权重的均匀变化，而`- n * arr[n - i]`删除从末尾换到前面的元素的过多计算贡献。 索引`arr[n - i]`对应于跟踪每次旋转后哪个元素成为新的第一个元素。 

变量`best`跟踪所有旋转的最大加权和。 

一个常见的陷阱是混合左右旋转约定。 递归假定方向一致，不正确的索引将默默地产生看似有效但错误的答案。

 ## 边缘情况

 对于单个厨师，该算法将初始加权和计算为该值的 1 倍，并且旋转循环不会改变任何内容，因此输出立即正确。 

对于相等的值，例如`5 5 5 5`，每次旋转都会产生相同的总和。 递归仍然产生相同的值，因为`total`等于`n * value`，使调整完全抵消。 

对于像这样的主导元素`[1000000000, 1, 1, 1, 1]`，尽早放置大值可以最大化乘数风险。 旋转更新正确地将该值移动到所有位置，确保在不显式重建每个排列的情况下找到最大值。
