 ## 解决方案
 ## 问题理解

 我们得到了一系列必须按固定顺序丢弃的小饰品。 每个小饰品都有重量，我们还有相同的垃圾袋，最大容量为$K$。 一个袋子可以连续存放多个饰品，只要它们的总重量不超过$K$。 一旦我们决定停止使用当前的袋子，它就会被扔掉，并使用一个新的空袋子。 任何时候我们都不允许保留超过一个部分装满的袋子，这意味着这个过程是严格顺序的：我们从左到右装满一个袋子，然后继续或关闭它并开始一个新的袋子。 

目标是尽量减少整个序列中使用的袋子数量。 

输入给出$N$，饰品的数量，然后按顺序排列它们的重量。 输出是在必须保留订单且每个袋子有容量的约束下包装所有小饰品所需的最小袋子数$K$。 

约束足够大，以至于二次或偶数$O(N \log N)$策略是不必要的开销。 和$N \le 10^5$， 一个$O(N)$贪婪扫描是 1 秒限制内唯一安全的目标。 任何尝试重新考虑以前的分组决策或模拟所有分区点的方法都会面临风险$O(N^2)$最坏情况下的行为，远远超出了可接受的限度。 

当单个 trinket 完全等于$K$。 既然如此，它就必须占据自己的包。 例如，输入：```
3 5
5 1 1
```正确的输出是`2`。 一个粗心的实现总是试图“先适应，后分割”而不仔细检查相等性，可能会尝试错误地组合或在满容量后错误地处理重置逻辑，从而导致错误的分组。 

另一种情况是当所有小饰品都非常小并且总和正好适合多个袋子时：```
5 3
1 1 1 1 1
```正确的行为是按顺序打包，仅在添加下一个元素将超出容量时重置。 

## 方法

 暴力策略将模拟将序列划分为有效的连续组的所有可能方法。 每组的总重量不得超过$K$。 这可以被认为是在饰品之间选择切点并检查每个片段是否有效。 有$N-1$潜在的削减位置，所以有$2^{N-1}$选择分割的方法。 即使我们只验证线性时间的分割，这种方法也会变得指数级并且立即不可行$N = 10^5$。 

一种稍微结构化的暴力方法将使用动态编程，其中$dp[i]$是第一次所需的最少行李数$i$小饰品。 对于每个$i$，我们尝试所有之前的位置$j < i$使得该段$(j+1..i)$适合一个袋子。 这可以正常工作，但仍然会导致$O(N^2)$在最坏的情况下，例如当所有权重都很小并且每个前缀都有效时，迫使每个状态扫描所有先前的状态。 

关键的观察结果是顺序是固定的，每个袋子的行为就像一个具有严格容量限制的滑动窗口。 一旦我们开始装满一个袋子，我们就永远不需要重新考虑之前的选择，因为除非下一个项目不再适合，否则提前分割有效的部分段没有任何好处。 这将问题变成了一个贪婪的打包过程：不断积累，直到添加下一个饰品超出容量，然后关闭袋子并开始一个新的。 

这种贪婪策略之所以有效，是因为同一连续段的不同有效包装之间没有成本差异； 唯一的目标是最小化段的数量，并且尽可能多地扩展段总是会微弱地减少所需的段的数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力DP |$O(N^2)$|$O(N)$| 太慢了 |
 | 贪心扫描 |$O(N)$|$O(1)$| 已接受 |

 ## 算法演练

 我们按顺序处理小饰品，保持当前袋子的累积重量以及我们已打开的袋子数量。 

1. 将行李计数器初始化为零，并将当前行李的运行总和初始化为零。 我们从没有活动包开始。 
2. 按顺序迭代每个饰品的权重。 
3. 对于每个饰品，检查将其添加到当前袋子中是否会超过$K$。 该检查是算法中唯一的决策点。 
4. 如果合适，请将重量添加到当前行李总和中并继续。 这可以在不违反限制的情况下使当前包尽可能满。 
5. 如果不适合，则增加行李计数器，因为当前行李已完成。 然后开始一个新包，将此饰品作为第一个物品。 
6.处理完所有饰品后，如果有部分装满的袋子，则在最后一次打开步骤时已隐式计数，因此无需额外调整。 

总是贪婪地填充背后的原因是，延迟袋子关闭永远不会对未来的元素有帮助，因为一旦容量固定并且订单是强制性的，未来的决策是独立的。 

### 为什么它有效

 在任何时刻，该算法都会维护一个活动包，其中包含适合容量的剩余序列的最大前缀$K$。 这是一个不变量：当前包始终包含从其开口点开始的最长可能的有效连续段。 当新元素不适合时，当前包无法扩展，因此必须强制启动新包。 

任何提前关闭袋子的替代解决方案只能增加袋子的数量，因为它减少了有效段的大小，而无法对饰品进行任何重新排列或重新排序。 因此，贪心构造会产生尽可能少的段数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))
    
    bags = 0
    cur = 0
    
    for w in arr:
        if cur + w > k:
            bags += 1
            cur = w
        else:
            cur += w
    
    if n > 0 and cur > 0:
        bags += 1
    
    print(bags)

if __name__ == "__main__":
    solve()
```该实现保持运行总和`cur`对于当前的包。 当无法添加下一个重量时，我们通过递增来最终确定当前的包`bags`并重新开始积累。 一个微妙的点是最终未完成的包：因为我们只增加`bags`当关闭一个完整的袋子时，如果当前袋子中放置了任何小饰品，我们必须在最后添加一个。 

该逻辑确保每个饰品都属于一个袋子，并且每个袋子都遵守容量限制。

 ## 边缘情况

 一个关键的边缘情况是每个饰品都与容量完全匹配$K$。 例如：```
3 5
5 5 5
```该算法为第一个项目启动一个袋子，当下一个项目无法容纳时立即关闭它，然后重复。 每个元素都成为自己的包，产生输出`3`。 贪婪逻辑自然地处理这个问题，因为每次加法都会触发溢出条件。 

另一种情况是当许多小物品堆积起来恰好装满一个袋子时：```
6 3
1 1 1 1 1 1
```运行总和变为 3，然后重置，产生两袋 (1,1,1) 和 (1,1,1)。 每个袋子都被最大程度地填充的不变性确保不会发生过早分裂。 

最后，混合情况如：```
5 4
3 1 2 2 1
```表明该算法从不尝试重新排列局部最优选择。 每个决定纯粹基于下一个项目是否适合，这已经足够了，因为顺序是固定的，并且提前拆分没有任何好处。
