 ## 解决方案
 ## 问题理解

 我们得到了两个序列的菜肴，每个菜肴都由一个大写字母表示。 第一个序列是桌子上的当前排列，第二个序列是所需的最终排列。 唯一允许的操作是交换两个相邻的盘子，我们希望使用尽可能少的交换将第一个序列转换为第二个序列。 如果根本无法做到，我们必须报告不可能。 

重要的限制是交换仅是相邻的，因此我们本质上正在使用使用反转将一个字符串转换为另一个字符串的经典概念。 然而，只有当两个序列包含完全相同的多组字母时，这才有效，因为交换不能创建或破坏盘子。 如果任何字符出现的次数不同，则不可能立即进行转换。 

输入量较小，最多100个菜品。 这意味着甚至二次或三次算法也是可以接受的。 模拟交换或尝试所有重新排序的解决方案仍然会通过，但我们的目标应该是彻底简化为已知结构。 

一些边缘情况很重要：

 如果两个字符串之间的字母频率不同，则即使可以部分对齐，答案也必须为 -1。 例如，改造`AAB`进入`ABC`是不可能的，因为没有`C`在源中。 

如果字符串已经相等，则答案为 0。 

如果所有字符都相同，则任何排列都是有效的，答案只是对齐相同序列所需的相邻交换数，该数始终为 0，因为它们无法区分。 

## 方法

 蛮力的想法是直接模拟该过程。 我们可以重复扫描字符串，找到不匹配的位置，并交换相邻的字符以将正确的字母推入到位。 每次交换都会减少局部的无序性，我们可以继续下去，直到字符串与目标匹配或者不可能取得任何进展。 

这是正确的，因为每个操作都是有效的，并且只有达到目标时我们才会停止。 问题在于，天真地模拟交换可能需要在 O(n) 个位置上移动角色，而对 O(n) 个角色执行此操作会导致 O(n²) 或更糟糕的行为。 当 n 达到 100 时，这仍然没问题，但它不是最干净的推理路径。 

一个更结构化的观点是将其视为倒置计数问题，但有一个转折：我们不是对任意数字进行排序，而是将序列与重复项和固定目标顺序对齐。 我们从左到右扫描源字符串，对于每个位置，我们决定应该匹配所需字符的哪个出现位置。 一旦我们修复了该配对，所需的交换次数正是由于将该事件移至适当位置而引起的反转次数。 

关键的观察是目标中的每个字符确定特定的目标位置，并且我们可以按顺序匹配出现的情况。 一旦确定了这种匹配，相邻交换的最小数量就是源订单和目标订单中所选位置之间的成对交叉数量。 这简化为计数问题而不是模拟问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力交换模拟| 最坏情况 O(n3) | O(n) | 已接受但没有必要 |
 | 匹配+反转计数| O(n²) | O(n) | 已接受 |

 ## 算法演练

 1. 首先通过检查两个字符串是否具有相同的字符数来验证可行性。 如果存在任何不匹配，则转换无法完成，因为交换不会更改字符多重集。 
2. 对于源字符串中的每个字符，构建其位置列表。 对目标字符串执行相同的操作。 这为我们提供了事件之间的确定性映射：第一个`A`源中必须对应第一个`A`在目标中，第二个到第二个，依此类推。 
3. 构造数组`p`在哪里`p[i]`是当前源位置字符的目标索引`i`。 这将问题转化为测量源排列与目标排列的距离。 
4. 计算数组中的反转数`p`。 每个反转完全对应于固定两个元素的相对顺序所需的一个相邻交换。 
5. 返回反转计数。 

反转解释之所以有效，是因为每个相邻的交换都精确地修复了一个反转，并且不会不一致地创建或破坏其他结构。 

### 为什么它有效

 修复相同字母之间的配对消除了歧义：我们不再选择哪个`A`匹配哪个`A`，我们通过出现索引强制顺序一致性。 一旦建立了这种映射，变换就变成了索引的排列。 将一种排列转换为另一种排列所需的最小相邻交换次数恰好是它们之间的反转距离，因为每个相邻交换都将反转计数精确地更改为 1，并且我们总是可以贪婪地减少反转，直到没有反转为止。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    t = input().strip()

    if sorted(s) != sorted(t):
        print(-1)
        return

    pos_s = {}
    pos_t = {}

    for i, c in enumerate(s):
        pos_s.setdefault(c, []).append(i)

    for i, c in enumerate(t):
        pos_t.setdefault(c, []).append(i)

    p = [0] * n
    for c in pos_s:
        for i, idx in enumerate(pos_s[c]):
            p[idx] = pos_t[c][i]

    inv = 0
    for i in range(n):
        for j in range(i + 1, n):
            if p[i] > p[j]:
                inv += 1

    print(inv)

if __name__ == "__main__":
    solve()
```该解决方案首先验证两个字符串是否包含相同的多组字符。 排序就足够了，因为 n 很小并且它提供了直接的相等检查。 

然后我们记录两个字符串中每个字符的出现索引。 这很重要，因为重复项必须一致匹配； 否则，不同的配对可能会导致不同的交换计数。 

数组`p`编码每个源位置必须以目标顺序结束的位置。 一旦建立了这种排列，剩下的问题就纯粹是组合问题了：计数反转。 

由于 n 只有 100，反转计数循环以最简单的方式实现。芬威克树也可以工作，但这里没有必要。

 ## 边缘情况

 一个关键的边缘情况是字符大量重复。 例如`AAAAAB`到`BAAAAA`。 该算法正确地按顺序分配出现的事件，因此单个`B`一致匹配，并且所有反转都相对于该固定身份进行计数。 天真的贪婪交换可能会意外地对待相同的`A`可以互换并且仍然得到正确的答案，但是如果没有一致的映射，很容易在更复杂的混合中错误地计算交换。 

另一种边缘情况是由于缺少字母而完全不可能。 可行性检查通过频率比较立即捕获这一点，确保部分匹配不会导致错误的数字答案。
