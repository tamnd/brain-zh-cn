 ## 解决方案
 ## 问题理解

 我们有一个测验系统，其中每个问题都通过从一组固定选项中精确选择一个选项来回答。 每个选择都有一个数值，测验的总结果只是所有问题中所选值的总和。 重要的是，每个问题都共享相同的可能值列表，因此结构是统一的：我们对 n 个问题中的每个问题独立地重复相同的选择过程。 

一旦形成总分，它就会与几个不相交的数字区间相匹配，每个区间对应于一种特定的食物。 对于每种食物，我们必须确定是否存在至少一种方法来回答测验，使得所得总和落在该食物的区间内。 

因此，核心计算任务不是明确构建所有答案，而是了解在从同一多组值中进行 n 次独立选择后可以实现哪些总和，然后检查这些和在给定范围内的成员资格。 

这些约束足够小，足以强烈建议采用状态空间动态规划解决方案。 n和m都最多为20，则总选择数最多为20步，每步最多提供20个选择。 所有 m^n 可能性的任何指数计数都会增长为 20^20，这远远超出了可行的极限。 但是，最大可能总和受到严格限制：每个值最多为 20，因此最大总和为 400。这使得跟踪小整数范围内的可达性成为可能。 

可能导致错误解决方案的一个微妙问题是忘记不同的序列可以导致相同的总和。 将序列视为不同的序列是不必要且昂贵的； 只有可实现的金额才重要。 另一个常见的错误是假设贪婪的构建工作，例如总是选择每个问题的最小值或最大值。 但这会失败，因为中间组合可以解锁纯粹极端无法达到的总和。 例如，对于值 [1, 10] 且 n = 2，总和 11 是可以实现的，但如果贪婪策略对每个问题进行本地推理，则可能会错误地错过此类组合。 

## 方法

 天真的方法是列举所有可能的回答测验的方法。 n 题每题都有 m 个选择，因此完整答题纸的总数为 m^n。 对于每个，我们计算一个总和并将其标记为可达。 这是正确的，因为它显式地构造了每种可能性，但其运行时间呈指数增长。 当 m 和 n 都达到 20 时，这就变成了 20^20 种组合，这远远超出了任何可行的计算。 

关键的观察结果是，问题的顺序对于总和并不重要，并且在每一步中都会重复使用相同的值集。 这将问题转化为重复求和集构造：从仅包含 0 的集合开始，我们重复添加一层，将 v 中的每个值添加到所有先前可达到的和中。 经过 n 层之后，我们获得了所有可实现的总数。 由于最大和只有 400，我们可以安全地在和上维护一个布尔 DP 并迭代 n 次。 

这将问题从序列上的指数枚举减少到有界状态空间上的多项式时间传播。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(m^n · n) | O(m^n · n) | O(1) | O(1) | 太慢了 |
 | 最佳DP | O(n·m·S)，其中 S ≤ 400 | O(S)| 已接受 |

 ## 算法演练

 ## 最优 DP 构建

1. 初始化一个布尔数组 dp，其中 dp[s] 表示在处理一定数量的问题后是否可以得到总和 s。 设置 dp[0] = true 因为在回答任何问题之前，总和为零。 
2. 将以下过程重复 n 次，每个问题一次。 每次迭代都表示在总和中再添加一个选定的值。 
3. 对于每次迭代，创建一个新数组 next_dp 并初始化为 false。 该数组将存储回答一个问题后可获得的所有总和。 
4. 对于每个使 dp[s] 为 true 的和 s，尝试用每个可能的值 v_i 来扩展它。 将 next_dp[s + v_i] 标记为 true。 这对应于为当前问题选择答案 v_i。 
5. 处理完所有和和值后，将 dp 替换为 next_dp。 这确保了每一层仅使用前几个问题的结果，避免在同一步骤中意外重复使用。 
6. 完成所有n次迭代后，dp对所有可能的最终分数进行编码。 
7. 对于每个食物区间 [l, r]，检查该范围内是否存在任何 s 使得 dp[s] 为真。 如果存在这样的总和，则答案是“是”； 否则不。 

我们可以安全地独立扫描每个区间的原因是，每个食物决策仅取决于至少一个有效总和的存在，而不取决于存在多少个这样的总和或它们如何与其他区间重叠。 

### 为什么它有效

 DP 保持了以下不变式：在 i 次迭代之后，dp 准确地表示使用 i 个问题选择可实现的所有总和。 每个转换都从允许的值集中添加一个选择，从而保持正确性，因为长度为 i + 1 的每个有效序列都可以分解为长度为 i 的有效序列加上一个最终选择。 相反，每个构造的转换都对应于一个真实的选择序列。 转换和有效答案序列之间的这种双射保证了完整性和可靠性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    v = list(map(int, input().split()))
    q = int(input())
    intervals = [tuple(map(int, input().split())) for _ in range(q)]

    max_sum = n * max(v)
    dp = [False] * (max_sum + 1)
    dp[0] = True

    for _ in range(n):
        ndp = [False] * (max_sum + 1)
        for s in range(max_sum + 1):
            if not dp[s]:
                continue
            for val in v:
                if s + val <= max_sum:
                    ndp[s + val] = True
        dp = ndp

    for l, r in intervals:
        ok = False
        for s in range(l, r + 1):
            if 0 <= s <= max_sum and dp[s]:
                ok = True
                break
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```该实现直接反映了 DP 构造。 dp 数组在每一步都会重新分配，以防止不同问题计数的状态混合。 边界检查确保我们的索引永远不会超出最大可能总和 n · max(v)。 间隔检查是通过简单的扫描完成的，因为总范围足够小，甚至完全遍历也是微不足道的。 

一个常见的陷阱是尝试就地更新 dp。 这将错误地允许同一问题多次使用
