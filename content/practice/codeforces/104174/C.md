 ## 解决方案
 ## 问题理解

 我们得到一个由小写拉丁字母组成的字符串。 从这个字符串中，我们可以通过重复选择一个字符，将其写下来，然后将剩余的字符串分成严格位于其左侧的部分和严格位于其右侧的部分来构造新的字符串。 然后，我们按顺序独立地将相同的过程应用于两个部分。 每个完整的选择序列都会生成一个最终字符串，该字符串由原始字符串的所有字符按某种顺序组成，但不是任意排列：该顺序受到围绕所选枢轴的递归分割的约束。 

任务是确定这个递归“选择一个主元并在两侧递归”过程可以生成的字典顺序最小的字符串。 

该约束允许字符串长度最大为 200,000，这会立即排除任何尝试模拟所有可能选择甚至所有段排列的解决方案。 任何根据选择进行分支或每一步构造多个候选字符串的方法都将呈指数级增长。 我们需要更接近线性或近线性行为，通常为 O(n log n) 或 O(n)。 

一个微妙的边缘情况是，重复的字符允许多个有效的主元选择，这可能会导致不同的结构分解。 例如，在像“bbaacc”这样的字符串中，选择相同最小字符的不同出现会改变分区模式，并且在不仔细推理结构的情况下，天真贪婪地选择最左边的出现显然并不安全。 

另一个不明显的陷阱是假设这相当于对字符串进行排序。 它不是。 递归限制了哪些字符可以与其他字符交换，因此输出不一定只是经过排序的字符多重集，即使在某些情况下它与之一致。 

## 方法

 暴力解释是精确模拟该过程。 对于字符串段，我们选择每个可能的枢轴位置，递归计算左段和右段的结果，并将枢轴加上两个结果连接起来。 然后我们在所有选择中选取字典顺序最小的一个。 

这是可行的，因为它直接遵循定义，但速度非常慢。 对于长度为 n 的字符串，每个状态最多分为 n 个选择，每个选择又分为两个子问题。 由此产生的递归树的数量呈超指数增长。 即使记忆也不能保存它，因为不同的主元序列会产生不同的结构状态，并且不同子结构的数量通常仍然是指数级的。 

关键的观察结果是，该过程始终选择一个字符作为根，而其他所有字符都相对于它进行分区。 如果我们想要字典顺序最小的结果，我们应该尽量确保较小的字符尽早出现在最终输出中。 这表明了一种贪婪的结构选择：在每个阶段，我们应该选择当前段中的最小字符，因为任何较大的第一个字符都会立即使结果字符串在字典顺序上比以较小字符开头的字符串更糟糕。

一旦我们修复了最小的字符，它在段中的所有出现都只能在分区方面互换，但它们都会产生有效的分解。 关键的简化在于，最终答案可以通过始终采用最小的可用字符并将相同的逻辑递归地应用于其余部分来构建，同时保持由其原始位置引起的排序。 这将问题简化为重复提取最小字符并相应地分割剩余结构，这可以使用分段感知的贪婪遍历和类似堆栈的重建或使用下一个出现指针的分而治之来有效地实现。 

实际上，标准解决方案是将字符串视为间隔并重复选择当前间隔中的最小字符，然后在其左侧和右侧的子间隔上递归，始终保留顺序。 这可以使用线段树或 RMQ 结构在 O(n log n) 内完成。

 ## 算法演练

 我们将当前问题表示为从子串区间构建答案，始终在结构约束下提取最佳的下一个字符。 

1. 在字符串上预先计算一个范围最小查询结构，该结构可以返回任意区间中最小字符的位置。 我们需要它来快速决定哪个字符可以按字典顺序放置在下一个。 
2. 定义一个递归函数solve(l, r)，返回从子字符串s[l:r+1] 中可获得的最佳字符串。 该函数的目标是构建尊重分割规则的最佳序列。 
3. 在solve(l, r)中，使用RMQ结构找到s[l:r+1]中最小字符的位置m。 该字符被迫成为该段的所有有效结构中的第一个，因为任何将较大字符放置在前面的有效结构在字典顺序上都会更差。 
4. 在答案中添加 s[m]。 
5. 递归左段solv(l, m-1)。 这会产生最初位于所选枢轴左侧的字符的最佳可能排序。 
6. 递归右段solve(m+1, r)。 这会产生右侧字符的最佳可能排序。 
7. 按照左、中枢、右的顺序连接结果，尊重递归如何定义原始拆分过程中的构造顺序。 

### 为什么它有效

 递归不变式是，对于任何段，我们总是尽可能早地将该段中最小的可用字符放置在结果字符串中。 与选择较小字符的有效结构相比，任何偏离首先选择最小字符的行为都会立即引入字典顺序上更大的前缀。 修复枢轴后，左右部分是独立的子问题，因为除非通过递归调用，构造过程绝不会跨所选枢轴边界混合字符。 这确保了最佳子结构：区间的最佳解决方案由其子区间的最佳解决方案组成。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, s):
        self.n = len(s)
        self.s = s
        self.seg = [(chr(127), -1)] * (4 * self.n)
        self._build(1, 0, self.n - 1)

    def _better(self, a, b):
        return a if a[0] < b[0] or (a[0] == b[0] and a[1] < b[1]) else b

    def _build(self, v, l, r):
        if l == r:
            self.seg[v] = (self.s[l], l)
            return
        m = (l + r) // 2
        self._build(v * 2, l, m)
        self._build(v * 2 + 1, m + 1, r)
        self.seg[v] = self._better(self.seg[v * 2], self.seg[v * 2 + 1])

    def query(self, v, l, r, ql, qr):
        if ql > r or qr < l:
            return (chr(127), -1)
        if ql <= l and r <= qr:
            return self.seg[v]
        m = (l + r) // 2
        return self._better(
            self.query(v * 2, l, m, ql, qr),
            self.query(v * 2 + 1, m + 1, r, ql, qr)
        )

def solve():
    s = input().strip()
    n = len(s)
    st = SegTree(s)

    sys.setrecursionlimit(10**7)

    def dfs(l, r):
        if l > r:
            return ""
        ch, idx = st.query(1, 0, n - 1, l, r)
        return ch + dfs(l, idx - 1) + dfs(idx + 1, r)

    print(dfs(0, n - 1))

if __name__ == "__main__":
    solve()
```线段树为每个节点存储该线段中的最小字符及其索引，这是重建正确的分割所必需的。 每个递归调用都使用查询来查找对数时间内的枢轴位置，然后分为左右间隔。 

一个微妙的实现细节是返回字符和索引，因为相同的字符必须一致地排序，否则递归可能会选择不一致的主元并破坏确定性。 

递归首先连接左侧结果，然后连接主元，然后连接右侧结果，匹配围绕所选字符拆分的结构定义。

 ## 边缘情况

 关键的边缘情况是字符串由重复的相同字符组成。 在这种情况下，每个字符都是有效的主元，并且递归应该一致地选择一个索引而不影响正确性。 通过索引打破线段树的平局确保了确定性选择，因此对于输入`aaaa`，每次递归调用都会选择最左边的`a`，递归简单地线性剥离字符串，产生`aaaa`。 

另一种边缘情况是严格递减的字符串，例如`dcba`。 算法总是会选择`a`首先在顶层，然后递归地分解剩余的段。 每次递归继续选择最小的剩余字符，产生`abcd`。 段分割保证没有反转存在。 

第三种情况是交替模式，例如`ababab`。 这里，不同位置存在多个相同的最小值。 索引决胜局确保稳定的分裂，防止不一致的分区，并且递归构建平衡的分解，仍然产生字典顺序上最小的有效重建。
