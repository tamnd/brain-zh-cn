 ## 解决方案
 ## 问题理解

 我们给出了一个排列`p`的数字`1...n`。 另一个数组`a`包含`m`全部出现在排列中的不同值。 

对于每个值，我们只关心它在排列中的位置。 让`pos[x]`成为价值指标`x`在`p`。 

数组`a`当每个连续的对都满足时，称为 _ 不好`pos[a[i]] < pos[a[i+1]] ≤ pos[a[i]] + d`。 

换句话说，当我们经过`a`，每个下一个元素必须出现在前一个元素的右侧，但不能超过`d`位置远离。 

我们可以交换排列的相邻元素。 每个相邻的交换花费一次移动。 目标是找到完成任务所需的最少步数`a`变好，意味着至少有一对连续的违反了条件。 

关键的观察是整个数组的条件只是每个相邻对的条件的合取。 即使其中一对无效，整个阵列也会变得良好。 

制约因素很大。 总和为`n`所有测试用例最多`5 · 10^5`，因此任何比粗略线性或慢的解决方案`O(n log n)`每个测试用例太贵了。 直接模拟交换是不可能的，因为单个答案可能需要多次交换，并且测试用例多达一万个。 

一些边缘情况很容易被忽略。 

考虑：```
n=4, d=2
p=[1,2,3,4]
a=[1,4]
```这里`pos(1)=1`,`pos(4)=4`。 该对已经违反了所需的距离约束，因为`4 > 1+2`。 数组已经好了，所以答案是`0`。 任何假设每对都必须独立修复的解决方案都会产生肯定的答案。 

另一个微妙的情况是，将右侧元素移到更右侧似乎很便宜，但没有足够的空间。```
n=5, d=3
p=[1,2,3,4,5]
a=[1,3]
```我们有岗位`(1,3)`。 通过推动打破条件`3`是的，我们需要它才能到达位置`5`，要求`2`互换。 这是有效的，因为位置`5`存在。 

现在改变排列长度：```
n=4, d=3
p=[1,2,3,4]
a=[1,3]
```目标位置将是`1+3+1=5`，它位于数组之外。 向右推是不可能的，尽管所需交换的公式仍然给出`2`。 正确的解决方案必须验证是否存在足够的空闲位置。 

第三个陷阱是忘记向左移动一个元素也会改变其他位置。```
n=6, d=4
p=[1,2,3,4,5,6]
a=[2,5]
```移动`5`正确的成本`2`互换。 移动`2`向右或`5`向左对相对顺序的影响不同。 最低限度的答案来自于仔细分析两种可能性，而不是贪婪地选择一个方向。 

## 方法

 暴力方法会尝试每一个相邻的对`a`，模拟交换，并计算需要多少次移动才能使该对违反条件。 即使将注意力限制在单个货币对上，也存在许多可能的交换序列。 明确地探索它们很快就变得不可行。 

蛮力之所以有吸引力的原因是，一旦相邻的一对不符合所需的关系，数组就会变得很好。 不幸的是，可能的交换序列的数量呈爆炸性增长，甚至模拟所有相关的运动也将花费二次或更糟的时间。 

条件的结构提供了更强有力的观察。 一对```
x = a[i]
y = a[i+1]
```只有他们的立场才重要。 

让```
px = pos[x]
py = pos[y]
```如果```
py <= px
```或者```
py > px + d
```那么这对已经违反了条件，所以整个数组已经很好并且答案立即`0`。 

有趣的案例是```
px < py <= px + d
```其中该对当前满足禁止关系。 

要打破它，只有两个有意义的选择。 

我们可以移动`y`向右直到```
py > px + d.
```所需的交换次数为```
(px + d + 1) - py.
```或者，我们可以移动`x`向右移动，直到到达或经过`y`， 制作```
px >= py.
```那成本```
py - px.
```第二种选择并不总是可行。 移动`x`右要求区间边界之间有足够的空闲位置。 禁止窗口占用的区间有长度`d+1`，如果已经挤得太紧了，就无处可动了。 

关键的见解是只需要破坏一对。 我们可以独立计算每个相邻对的最小成本`a`并取最小可行值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) 或更糟 | O(n) | 太慢了|
 | 最佳 | O(n + m) | O(n) | 已接受 |

 ## 算法演练

 1. 构建逆排列`pos`， 在哪里`pos[value]`存储该值的当前位置。 
2. 将答案初始化为一个非常大的数字。 
3. 对于每一个相邻的对`(a[i], a[i+1])`，计算：```
px = pos[a[i]]
py = pos[a[i+1]]
```4.如果```
py <= px
```那么这对已经违反了所需的排序。 整个数组已经很好了，所以答案是`0`。 
5.如果```
py > px + d
```那么这对已经违反了距离限制。 整个数组已经很好了，所以答案是`0`。 
6. 否则该对当前满足禁止关系。 计算搬家费用`y`正确的：```
cost_right = px + d + 1 - py
```7. 检查该运动是否确实可行。 推`y`就在`cost_right`位置，我们需要在右侧有足够的单元格`y`。 

目标位置是：```
px + d + 1
```所以它必须满足```
px + d + 1 <= n
```8. 即使目标位置存在，移动`y`权利消耗位置。 间隔从`px`到`px+d`已经包含```
py - px - 1
```之间的元素`x`和`y`。 

该区间之外的可用空闲头寸是```
n - 1 - px
```相对于运动要求。 

社论中导出的标准可行性条件变为：```
n - py >= cost_right
```这相当于```
n - py + 1 > cost_right.
```9. 如果移动可行，则将答案更新为```
min(answer, cost_right)
```10. 另一种选择是搬家`x`直到它到达`y`。 这需要花费```
py - px
```互换。 

仅当有足够的空间来执行此操作而不违反排列结构时，此操作才可行。 众所周知的条件简化为：```
d - (py - px) >= py - 1
```这与公认的解决方案中使用的可行性检查完全相同。 
11. 在实践中，公认的解决方案将这些条件组合到一个测试中：```
if n - py + 1 > cost_right and px + d <= n:
    answer = min(answer, cost_right)
```并且总是比较```
py - px
```当向右运动不可能时。 
12. 取所有相邻对的最小值。 

### 为什么它有效

 一旦相邻的一对不符合禁止关系，该数组就会变得良好。 由于每对在定义上都是独立的，因此找到最便宜的对来打破就足够了。 

对于有效的禁止对，只有两种方法使其无效。 要么正确的元素移动到距离之外`d`，或者左边的元素追上并破坏了严格的排序。 相邻的交换每次移动都会改变位置一次，因此所需交换的数量等于跨越相应边界所需的位置变化。 

可行性检查保证所需的运动实际上可以在排列内实现。 在打破每个相邻对的所有可行方法中，采用最小成本给出了最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    INF = 10 ** 18
    answers = []

    for _ in range(t):
        n, m, d = map(int, input().split())
        p = list(map(int, input().split()))
        a = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, x in enumerate(p):
            pos[x] = i + 1

        ans = INF

        for i in range(m - 1):
            px = pos[a[i]]
            py = pos[a[i + 1]]

            if py <= px or py > px + d:
                ans = 0
                break

            direct = py - px
            ans = min(ans, direct)

            need = px + d + 1 - py

            if px + d <= n and (n - py) >= need:
                ans = min(ans, need)

        answers.append(str(ans))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```第一部分构建逆排列。 这会将每个值查找转换为`O(1)`时间。 

对于每一个相邻的对`a`，我们立即检查它是否已经违反了禁止条件。 如果是这样，则不需要交换，我们可以停止处理该测试用例。 

当该对满足禁止条件时，我们计算两个候选成本。`direct = py - px`相当于移动左边的元素直到到达右边的元素。`need = px + d + 1 - py`对应于将右侧元素推到允许的距离之外。 

微妙的部分是可行性测试：```
if px + d <= n and (n - py) >= need
```第一个条件保证目标位置存在。 第二个保证右侧有足够的位置`y`对于所有必需的交换。 

缺少任何一项检查都会在几个隐藏测试中产生错误的答案。

 ## 边缘情况

 考虑：```
1
2 2 1
1 2
2 1
```我们有`px=2`,`py=1`。 自从`py <= px`，禁止关系已经被打破了。 算法立即返回`0`不考虑任何交换。 

考虑：```
1
4 2 1
1 2 3 4
1 4
```这里`px=1`,`py=4`。 自从`4 > 1+1`，距离条件已经失效。 算法再次返回`0`。 

考虑：```
1
4 2 3
1 2 3 4
1 3
```我们得到：```
px=1
py=3
need=2
```目标位置将是`5`，它不存在。 可行性检查拒绝了该选项。 该算法回退到替代成本`py-px=2`，这是正确答案。 

这些情况正是许多不正确的解决方案失败的地方，要么忽略已经无效的对，要么假设每个计算的移动实际上可以在排列内执行。
