 ## 解决方案
 ## 问题理解

 我们得到两个等长的字符串，并且允许我们以非常具体的方式修改第一个字符串。 每次我们更改第一个字符串中的字符时，该位置的原始字符都会被“记录”到一个特殊的集合中。 该集合跟踪我们曾经覆盖过的原始字符，并且其大小受到限制$k$。 

在所有修改结束时，我们将修改后的第一个字符串与第二个字符串进行比较。 我们计算它们之间有多少相同的子字符串，并且我们希望最大化该计数，同时确保添加到记录集中的不同字符的数量不超过$k$。 

重新解释操作的一个有用方法是，每个位置要么保留其原始字符，要么通过支付将该字符添加到集合中的成本来“原谅”。 一旦某个字符进入集合中，该字符的所有出现都可以自由修改，无需额外费用。 

关键的结构观察是集合约束是字符上的全局约束，而不是位置上的约束。 由于初始字符串中最多有 10 个不同的字符，因此任何决定实际上都是关于选择我们愿意“花费”预算的这些字符的子集。 

这些约束意味着子集上的组合爆炸仍然是可行的。 最多10个字符，最多有$2^{10} = 1024$子集，以及$n$所有测试用例的总和是$10^5$，所以一个$O(n \cdot 2^{10})$解决方案是可以接受的。 任何平方项$n$会立即失败。 

出现微妙的边缘情况时$k = 0$。 在这种情况下，我们永远无法修改原始值与目标对齐不同的字符，这意味着答案仅取决于位置$a[i] = b[i]$。 假设我们可以自由地覆盖不匹配的天真的方法会在这里产生不正确的结果。 

另一个极端情况发生时$k$足够大以覆盖所有不同的字符$a$。 然后我们可以不受限制地有效地改变任何位置，使得最优结果仅依赖于结构对齐$b$，任何假设局部决策的部分贪婪逻辑都可能会错过全局最优值。 

## 方法

 暴力解决方案将尝试各种方法来选择要修改的位置以及哪些字符最终出现在禁止集中$Q$。 对于每个配置，我们将模拟最终的字符串并计算匹配的子字符串$b$。 这立即变得不可行，因为即使对于固定的$k$，位置子集的数量呈指数增长$n$，子串计数本身是$O(n^2)$。 即使输入很小，总的复杂性也会崩溃。 

关键的简化是将焦点从位置转移到角色。 由于成本是根据修改中使用的每个不同的原始字符而不是每次操作而产生的，因此问题就变成了从最多 10 个可用字符中选择一个子集。$a$。 一旦子集被固定，我们就可以将包含这些字符的所有位置视为可自由修改。 

对于任何选定的子集，我们可以通过将问题简化为位置上的二元分类来有效地计算可实现的最佳匹配子串数量：在每个索引处，我们要么强制与$b[i]$或者我们将其视为灵活的并尝试最大化贡献。 

关键的见解是子串相等计数可以转化为对对的贡献进行计数$(l, r)$，这相当于对满足前缀约束的运行进行求和。 这导致了标准的减少：我们不是直接计算子字符串，而是根据是否保持前缀相等来计算有多少位置是“好的”。 

因为字符集很小，所以我们迭代所有字符子集$a$，模拟所得的最佳对齐，并取最大值。

 | --- | --- | --- | --- |
 | 蛮力 | 指数在$n$|$O(n)$| 太慢了|
 | 最佳 |$O(n \cdot 2^{10})$|$O(n)$| 已接受 |

 ## 算法演练

 我们首先将不同字符的集合压缩为$a$，因为只有那些对决策很重要。 设他们的计数为$m \le 10$。 

1. 分配每个不同的字符$a$从 0 到的索引$m-1$。 这允许我们将任何子集表示为位掩码。 这样做的原因是所有操作仅取决于角色是否被“激活”进行修改，而不取决于特定于位置的行为。 
2. 预先计算一个数组，为每个位置标记是否$a[i]$等于$b[i]$。 这捕获了没有任何修改的基线贡献。 
3. 迭代所有字符子集$a$使用位掩码。 对于每个掩码，将其解释为我们选择包含在其中的字符集$Q$。 如果选择的字符数超过$k$，我们立即丢弃这个掩码，因为它违反了约束。 
4.对于固定mask，模拟每个位置的效果：如果$a[i]$是在mask中，我们可以自由改变它来匹配$b[i]$，因此该位置变得“可固定”。 如果不是，则该位置将被锁定，并且只有在已经相等的情况下才会贡献。 
5. 将结果数组转换为增益数组，其中每个位置贡献 1（如果可以使其等于）$b[i]$，否则为 0。问题简化为计算该数组完全支持多少个子字符串。 
6. 通过从左到右扫描并保持当前有效段的长度来计算有效子串的数量。 每次我们扩展一个有效的长度段$L$，我们添加$L$因为以该点结尾的所有后缀子字符串都是有效的。 
7. 跟踪所有掩码的最大值。 

核心思想是，对于可修改字符的固定选择，有效性变成了位置上的简单连续结构问题，并且子串计数崩溃为线性累积。 

### 为什么它有效

 对于任何固定的字符子集，每个位置独立地变得完全可纠正或永久受限。 这种独立性确保子串的有效性仅取决于子串中的所有位置是否可纠正或已经匹配。 线性扫描正确地计算所有有效子串，因为每个有效结束位置准确地贡献了当前连续段内有效起始位置的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = input().strip()
        b = input().strip()

        # compress characters of a (at most 10 distinct)
        chars = list(set(a))
        m = len(chars)
        idx = {c: i for i, c in enumerate(chars)}

        # precompute equality
        eq = [1 if a[i] == b[i] else 0 for i in range(n)]

        ans = 0

        # iterate all subsets of characters in a
        for mask in range(1 << m):
            if mask.bit_count() > k:
                continue

            # build transformed validity array
            ok = [0] * n
            for i in range(n):
                if eq[i]:
                    ok[i] = 1
                else:
                    if mask & (1 << idx[a[i]]):
                        ok[i] = 1

            # count valid substrings in ok array
            cur = 0
            total = 0
            for i in range(n):
                if ok[i]:
                    cur += 1
                    total += cur
                else:
                    cur = 0

            ans = max(ans, total)

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先压缩字母表$a$因为整个决策空间仅取决于这些字符。 位掩码循环枚举要包含在修改集中的所有有效字符选择，修剪超出的任何掩码$k$。 

对于每个掩码，我们构建一个二进制数组，表示哪些位置可以等于$b$。 如果一个位置已经匹配，那么它总是好的； 否则，只有当其特征处于所选面具中时，它才会变得好。 这直接编码了操作约束的效果。 

子串计数步骤使用标准技术来计算二进制数组中所有子数组的贡献：连续的长度游程$L$贡献$L(L+1)/2$子串，作为运行总和递增累积。 

## 工作示例

 考虑一个简单的情况，其中$a = \texttt{abc}$,$b = \texttt{abd}$， 和$k = 1$。 

我们枚举字符上的蒙版$\{a,b,c\}$。 

| 面膜| 允许的字符 | 有效数组 | 总子串 |
 | --- | --- | --- | --- |
 | 000 | 000 {} | 110 | 110 3 |
 | 001| {c} | 111 | 111 6 |
 | 010| {b} | 110 | 110 3 |
 | 100 | 100 {一} | 110 | 110 3 |

 最好的选择是屏蔽字符$c$，它允许在位置 3 处进行完全校正，从而产生所有有效的子字符串。 

现在考虑一个没有灵活性的情况，$k=0$,$a=\texttt{abc}$,$b=\texttt{abd}$。 

| 面膜| 允许的字符 | 有效数组 | 总子串 |
 | --- | --- | --- | --- |
 | 000 | 000 {} | 110 | 110 3 |

 无法进行修改，因此只有已经匹配的位置才会起作用，并且答案是固定的。 

这些示例表明，最佳掩码选择直接决定了可以修复哪些不匹配，而子串计数是该选择的确定性结果。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = input().strip()
        b = input().strip()

        chars = list(set(a))
        idx = {c:i for i,c in enumerate(chars)}
        eq = [1 if a[i]==b[i] else 0 for i in range(n)]

        best = 0
        for mask in range(1<<len(chars)):
            if mask.bit_count() > k:
                continue
            ok = [0]*n
            for i in range(n):
                if eq[i] or (mask & (1<<idx[a[i]])):
                    ok[i]=1
            cur = ans = 0
            for v in ok:
                if v:
                    cur += 1
                    ans += cur
                else:
                    cur = 0
            best = max(best, ans)

        out.append(str(best))
    return "\n".join(out)

# sample checks (abbreviated style)
assert run("1\n3 1\nabc\nabd\n") == "6"
assert run("1\n3 0\nabc\nabd\n") == "3"
assert run("1\n3 10\nabc\nabd\n") == "6"
assert run("1\n4 1\nabcd\naxcb\n") == "6"

 ## 边缘情况

 当$k = 0$，掩码循环只允许空集，因此算法简化为扫描原始相等数组。 输入时$a=\texttt{abc}$,$b=\texttt{abd}$，有效数组是$110$，恰好生成 3 个子字符串，与预期行为相匹配。 

什么时候$k$很大，例如$k \ge m$，完整掩模变得有效，并将每个位置变成可能可校正的位置。 为了$a=\texttt{xbb}$,$b=\texttt{xcd}$，选择所有字符可确保所有位置都可以对齐，从而产生最大子串计数。
