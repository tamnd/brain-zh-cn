 ## 解决方案
 ## 问题理解

 我们有一个系统$w$垂直线从左到右编号。 每次操作都会在特定高度的两根相邻电线之间插入或移除水平连接器。 如果我们想象从电线顶部掉落一个令牌$i$，每次遇到活动连接器时$x$和$x+1$，它交换两侧并继续向下。 

因此，在处理完所有活动连接器之后，每个起始位置$i$最终到达某个最终位置，形成一个排列$[1..w]$。 每次更新都会切换一个连接器，每次更新后我们必须确定必须删除多少个当前活动的连接器，以便引发的排列成为身份排列。 

同样，在每个步骤之后，我们都可以删除一些当前活动的交换，并且我们希望删除的数量最少，以便应用剩余的交换（按固定的垂直顺序）不会产生净移动。 

约束条件$w \le 20$是关键信号。 排列空间足够小，我们可以将“系统的当前状态”视为有限但结构化的状态空间的元素，并将更新视为这些状态之间的转换。 更新数量$q$很大，因此一旦结构准备好，每次更新都必须在大致恒定或对数时间内处理。 

简单的模拟会在每次切换后跟踪排列，然后尝试计算要删除的最佳交换子集，但这很快就会陷入组合爆炸，因为选择删除相当于搜索活动交换的子集。 

一个关键的边缘情况是交换仅通过全局交互而不是本地配对取消。 例如，即使没有单独的边被使用偶数次，相邻边上的三次交换也可以产生同一性。 

输入如下：```
3 1 3
1 1 2
2 2 3
3 1 2
```造成最终排列变成恒等的情况，但删除任何单个交换会破坏平衡。 贪婪的“取消相邻对”方法在这里失败，因为取消在时间或位置上并不纯粹是本地的。 

## 方法

 暴力的想法是维护当前的活动交换集并尝试它们的所有子集，按顺序模拟每个子集，并计算结果排列。 这是正确的，但完全不可行。 高达$2 \cdot 10^5$操作，甚至检查单个子集成本$O(w)$，并且有$2^k$最坏情况下的活动边的子集。 

更结构化的视图是固定交换的顺序（按高度）并观察唯一的自由度是保留还是删除每个交换。 所以任务就变成了：在所有操作子序列中，选择一个其组合排列为恒等的子序列，使其长度最大化。 

这将问题转化为排列的动态规划。 自从$w \le 20$，我们对待每个排列$[1..w]$作为一个国家。 从恒等开始，每个操作要么保持当前排列不变，要么应用相邻元素的转置。 我们希望在处理所有更新后保留的最大数量的返回到身份的操作。 

因此，我们在由相邻交换引起的排列图上运行 DP，为每个排列保持最佳可实现的“保留计数”。 每次更新都会切换一次交换，因此动态应用或删除转换。 

困难在于，排列的状态空间在理论上是巨大的，但问题依赖于这样一个事实：我们不是在探索任意排列，而只是探索那些通过长而结构化的相邻转置序列可到达的排列，并且通过 DP 进行剪枝使主动边界在实践中在约束下保持可管理性$w \le 20$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集的暴力破解 |$O(2^q \cdot w)$|$O(q)$| 太慢了 |
 | DP 排列 | (O(q \cdot w \cdot | S | )) |

 这里$|S|$表示 DP 期间维持的可达排列状态的数量。 

## 算法演练

 我们维护大小排列的映射$w$在处理当前更新前缀后实现该排列的最佳保留交换数。 

1. 从单一状态开始：分数为 0 的恒等排列。 
2、一一处理更新。 每次更新都会切换位置的交换$x$和$x+1$。 我们将其解释为在活动集中添加或删除换位。 
3. 对于每个当前的 DP 状态，我们将其原封不动地向前推进，以表示跳过当前的交换。 这相当于删除它。 
4. 对于每个状态，我们还考虑应用交换（如果切换后当前处于活动状态）。 应用它会产生一个新的排列，通过交换当前排列中的两个相邻元素而获得，并且我们将分数增加 1。 
5. 处理完两个选择后，我们通过仅保留每个结果排列的最佳分数来合并状态。 
6. 完成所有更新后，我们查看身份排列状态。 如果它的最好成绩是$k$，那么我们就找到了在返回身份的同时可以保留的最大交换子集。 答案是$q - k$，因为必须删除所有未保留的交换。 

### 为什么它有效

 保留交换的每个子集对应于按时间顺序应用的唯一操作子序列。 通过在每一步选择保留或删除决策，DP 显式枚举所有可能的结果排列。 由于每个决策都是局部正确的，并且所有状态均按最佳分数合并，因此不会丢失排列的有效构造。 身份状态准确地捕获了那些其净效应完全抵消的子序列，并且最大化保留操作最小化删除。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def apply_swap(perm, i):
    perm = list(perm)
    perm[i], perm[i+1] = perm[i+1], perm[i]
    return tuple(perm)

def solve():
    w, h, q = map(int, input().split())
    
    active = set()
    ops = []
    
    for _ in range(q):
        y, x1, x2 = map(int, input().split())
        x1 -= 1
        x2 -= 1
        i = min(x1, x2)
        
        if (y, i) in active:
            active.remove((y, i))
            ops.append((i, False))
        else:
            active.add((y, i))
            ops.append((i, True))
    
    dp = {tuple(range(w)): 0}
    
    for i, is_add in ops:
        new_dp = {}
        
        for perm, score in dp.items():
            if perm not in new_dp or new_dp[perm] < score:
                new_dp[perm] = score
            
            if is_add:
                nperm = apply_swap(perm, i)
                nscore = score + 1
                if nperm not in new_dp or new_dp[nperm] < nscore:
                    new_dp[nperm] = nscore
        
        dp = new_dp
    
    identity = tuple(range(w))
    best = dp.get(identity, 0)
    
    print(q - best)

if __name__ == "__main__":
    solve()
```核心结构是滚动字典`dp`将排列映射到可实现的最佳保留交换数。 帮手`apply_swap`执行单个相邻转置，这是任何操作对状态产生的唯一影响。 

切换处理确保当交换消失时，我们停止在将来的转换中应用它。 当它出现时，我们允许两种可能性：跳过它或应用它。 

最后的减法`q - best`将“形成身份的最大保留掉期”转换为“最小移除”。

此跟踪显示删除并不简单地对应于取消单个操作； 早期保留的交换仍然可以通过 DP 中的后续结构“撤销”。

 ## 边缘情况

 一个微妙的情况是交换仅通过组合而不是成对删除来取消。 例如，即使没有单独的边是孤立冗余的，相邻边上的三个交换也可以产生同一性。 DP 正确地处理了这个问题，因为它保持完整的排列状态而不是跟踪本地计数。 

另一种情况是重复切换同一位置。 该实现通过显式跟踪活动交换并确保交换被删除后，它不再应用于未来的转换来处理此问题。 这可以防止过时的转换在 DP 状态空间中持续存在。 

最后，只有在正确处理长交互链后才能实现身份的配置，因为每个中间排列都保留为 DP 状态，确保不会丢失有效的组合路径。
