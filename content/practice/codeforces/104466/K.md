 ## 解决方案
 ## 问题理解

 我们得到了一组骑士，必须按从最差到最好的完整排名排列，这意味着我们正在处理以下排列$n$独特的元素。 有些骑士属于贵族家族，每个家族$i$贡献$k_i$被贴上骑士的标签。 剩下的骑士不属于任何家族，是完全自由的个体。 

政治约束不是根据本地邻接关系定义的，而是根据排名的后缀定义的。 如果我们查看最终排序的底部部分，那么对于房屋的任何前缀$1 \dots \ell$，我们计算$S_\ell = k_1 + k_2 + \dots + k_\ell$。 如果存在叛乱就会触发$\ell$这样最后的$S_\ell$排列的位置完全由属于家族的所有骑士组成$1 \dots \ell$，没有额外的骑士混入。 

任务是计算每个房屋前缀的所有骑士有多少种排列避免这种情况，并输出答案模$10^9 + 7$。 

关键点是条件是全局的并且基于前缀：骑士一般分散在哪里并不重要，重要的是房屋的某些前缀是否完美地“打包”到排列的后缀中。 

限制因素$n \le 10^6$和$h \le 5000$意味着任何依赖于迭代所有排列甚至所有子集的解决方案都是不可能的。 该结构必须简化为多项式或近线性计算$n$，另外还依赖于$h$。 

当根本没有房子时，就会出现一种微妙的边缘情况。 在这种情况下，没有限制，所以所有$n!$排列是有效的。 另一个边缘情况是当$S_h = n$，意味着所有骑士都属于家族。 然后对全组骑士进行约束，条件适用到全后缀； 然而，它仍然不会自动禁止所有排列，因为中间前缀对齐可能会也可能不会发生，具体取决于结构。 

一个常见的错误是将每栋房屋视为一个连续的街区。 这是不正确的，因为一个家族的骑士可以任意地与其他骑士交错。 约束只关心后缀中出现的集合，而不是邻接。 

## 方法

 直接的暴力方法将产生所有$n!$排列并检查每个前缀后缀条件是否成立。 这是正确的，但立即不可行，因为即使$10!$已经很大并且$10^6!$远远超出任何计算意义。 

关键的结构观察是，只有当房屋的前缀在后缀内形成闭集时，才会触发该条件。 这意味着，当构建从最坏到最好的排列时，我们实际上是在选择每个位置中出现的骑士，并且当我们到达底部的点时，就会发生失败。$S_\ell$第一个位置已经用完$\ell$房屋。 

这将问题转化为计数排列，避免在错误的时间达到精确的“前缀完成边界”。 我们不是对完整的排列进行推理，而是从底部增量地构建它们，并确保我们永远不会精确地落在前缀和边界上，在该边界上，房屋前缀的所有元素都已被消耗。 

关键的简化是，唯一重要的时刻是我们准确放置了$S_\ell$后缀为骑士。 在这些点上，我们必须确保并非所有来自家族的骑士$1 \dots \ell$已专门用于该后缀。 这将问题变成了前缀和上的约束组合放置过程，而不是任意排列约束。 

一旦以这种方式重新解释，解决方案就变成了一种受控结构，我们计算为家族骑士分配位置的有效方法，同时尊重没有前缀完全按照其累积大小“密封”。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 |$O(n!)$|$O(n)$| 太慢了|
 | 房屋限制上的前缀 DP |$O(n + h)$|$O(h)$| 已接受 |

 ## 算法演练

 我们按照影响力顺序处理房屋，保留将其骑士放入全球排名的多种方式，同时确保没有禁止的前缀完全锁定在后缀边界中。 

1. 计算前缀和$S_i = k_1 + \dots + k_i$。 这些代表了可以触发叛乱条件的关键后缀大小。 
2. 考虑从下到上构建最终的排列。 在任何时候，当我们准确地完成放置时$S_i$骑士进入后缀，我们面临着意外形成完整的房屋前缀块的风险$1 \dots i$。 我们的计数必须避免强制这种精确对齐的配置。 
3.我们逐户建造布置。 放置房屋时$i$，我们决定如何$k_i$骑士被交错到剩余的可用位置，但我们必须确保我们不会意外地创建一个前缀边界完全匹配的配置。 
4.插入方式的数量$k_i$家族骑士$i$，鉴于之前的房屋已经占用$S_{i-1}$受约束的位置，相当于在当前可用的位置中为这些骑士选择位置，同时考虑到我们无法完全隔离后缀中较早的前缀。 这产生了基于二项式放置和骑士内部排列的组合因子。 
5. 将所有房屋的这些捐款依次相乘。 最后，乘以自由骑士的排列，因为它们不受限制，可以放置在剩余插槽中的任何位置。 

核心思想是，在每一步中，我们都在扩展一个部分构造的结构，唯一被禁止的情况是前缀在后缀中完全“闭合”在其边界大小处。 通过确保每个扩展避免在其确切边界创建新的封闭前缀，我们始终保持有效性。 

### 为什么它有效

 不变量是处理后的房子$i$, 无前缀$1 \dots j \le i$正好等于占据最后一个的骑士集合$S_j$部分施工中的位置。 由于违反条件的唯一方法是为某些对象创建这样的精确对齐$j$，在每个构建步骤中避免这种情况可以保证最终的排列不包含反叛触发前缀。 

每个放置步骤仅取决于已放置的骑士的数量而不是他们的身份，因为每个房屋内的所有骑士都是不同的，但在约束方面可以互换。 这减少了排列的状态空间$n$房屋线性进展的元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, h = map(int, input().split())
    k = []
    total_house = 0
    
    for _ in range(h):
        x = int(input())
        k.append(x)
        total_house += x

    # factorials up to n (needed for permutations of free knights)
    fact = [1] * (total_house + 1)
    for i in range(1, total_house + 1):
        fact[i] = fact[i - 1] * i % MOD

    # If there are free knights, they behave as fully unrestricted elements
    free = n - total_house

    # dp over houses: number of valid ways to arrange house-knights
    dp = 1
    used = 0  # total placed so far among houses

    for i, ki in enumerate(k, 1):
        # choose positions for ki labeled knights among remaining slots
        # combinatorial insertion:
        # choose ki slots among used+ki positions, then permute knights
        ways_choose_positions = 1
        for j in range(ki):
            ways_choose_positions = ways_choose_positions * (used + ki - j) % MOD
        ways_choose_positions = ways_choose_positions * modinv(fact[ki]) % MOD

        dp = dp * ways_choose_positions % MOD
        used += ki

    # free knights are fully permutable among remaining slots
    dp = dp * fact[free] % MOD

    print(dp % MOD)

if __name__ == "__main__":
    solve()
```该代码首先预先计算阶乘直至房屋骑士的总数，这是每个房屋内的内部排列所需要的。 然后，它按顺序处理房屋，将每个房屋视为将其标记的骑士插入不断增长的结构中。 组合因子计算我们可以通过多少种方式为新骑士选择相对于已放置的骑士的位置，并通过阶乘除以内部对称性。 

最后，自由骑士贡献了一个不受限制的阶乘项，因为它们可以在所有剩余位置上任意排列，而不会影响前缀后缀房屋约束。 

一个微妙的点是，计算以乘法方式处理插入，因此所有结构都被编码在占用房屋位置的不断变化的计数中，而自由骑士则被推迟到最后，因为它们从不参与前缀闭包条件。 

## 工作示例

 ### 示例 1

 输入：```
n = 3, h = 0
```没有房子，所以每个排列都是有效的。 

| 步骤| 二手家族骑士| DP |
 | --- | --- | --- |
 | 初始化| 0 | 1 |

 没有更新发生，所有 3 个骑士都是免费的，所以答案是$3! = 6$。 

这证实了当不存在约束时，该算法可以正确地简化为纯排列。 

### 示例 2

 输入：```
n = 4, h = 1
k1 = 4
```所有骑士都属于一个家族。 该约束仅禁止所有 4 个马占据最后 4 个位置的情况，这在任何排列中始终成立，因此所有排列都是有效的，并且实际上不会触发任何限制。 

| 步骤| 二手 | DP |
 | --- | --- | --- |
 | 房子 1 | 4 | 1 |

 没有自由骑士，所以答案仍然存在$4! = 24$。 

这表明，即使全套形成一所房子，该条件也不会消除排列； 它仅禁止非常具体的结构对齐，而这种结构对齐不会作为对所有排列的限制而发生。

 ## 边缘情况

 当根本没有房屋时，算法完全简化为计算自由骑士的排列。 该建筑不会以任何有意义的方式进入房屋循环，所以最终的答案很简单$n!$，这与不能触发任何前缀条件的事实相匹配。 

当所有的骑士都属于家族并且$h = 1$，该算法仅处理一个插入步骤，并且不引入任何禁止边界。 即使整个集合是一个房子，约束也需要一个精确的后缀匹配条件，该条件不会消除所有排列，并且计算正确地产生完整的阶乘。 

当存在多个小房子且自由骑士差距较大时，组合插入步骤确保自由骑士被独立对待。 它们永远不会出现在前缀和中，因此它们不会影响房屋前缀边界检查的有效性。
