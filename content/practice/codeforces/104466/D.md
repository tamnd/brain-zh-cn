 ## 解决方案
 ## 问题理解

 我们掷一系列标准 DnD 骰子。 输入告诉我们包含多少个 d4、d6、d8、d12 和 d20 骰子。 每个骰子都是公平的，每个面都从 1 到其边数进行编号。 

每个完整的卷产生一个总和。 不同总和的可能性并不相同，因为面值的许多不同组合可能会产生相同的总和。 任务是打印每个可能的总和，按从最高概率到最低概率的顺序排列。 如果两个总和具有完全相同的概率，则接受任一顺序。 

最大输入包含每种类型 10 个骰子，总共 50 个骰子。 对每个结果进行暴力枚举是不可能的。 即使只掷十个 d20 骰子也能创造$20^{10}$结果，而实际的最大输入远大于此。 该算法必须避免枚举单个卷。 

有用的观察是，尽管结果的数量很大，但可能的总和的数量却很小。 最小可能的总和是骰子的数量，因为每个骰子至少贡献 1。最大可能的总和是$$40 + 60 + 80 + 120 + 200 = 500.$$只能存在 451 个不同的和，这是很小的。 这强烈表明动态规划优于求和。 

一个容易犯的错误是假设可以使用浮点值来比较概率。 浮点舍入可能会错误地交换概率相等或极其接近的和。 例如，```
1 0 0 0 0
```产生总和 1、2、3 和 4，每个总和具有相同的概率。 正确的输出可能以任何顺序列出它们，但基于舍入浮点值的比较是不必要的。 计算达到每个总和的方法的数量可以完全避免这个问题。 

另一种微妙的情况是只有一个骰子存在时。```
0 0 0 0 1
```每个面都只出现一次，因此每个和都有相同的概率。 1 到 20 的任何排列都是有效的。 假设始终存在唯一排序的解决方案将错误地拒绝有效输出。 

最后一种边缘情况是存在许多骰子时。```
10 10 10 10 10
```可能的掷骰数是天文数字，因此存储概率或枚举结果是不可行的。 动态规划仅存储获得每个可实现总和的方法数量，其最大索引永远不会超过 500。 

## 方法

 最直接的解决方案递归地生成每个可能的滚动，计算其总和，并计算每个总数出现的次数。 这是正确的，因为每个结果都会被检查一次。 不幸的是，它的运行时间等于结果总数，在最坏的情况下是$$4^{10} \cdot 6^{10} \cdot 8^{10} \cdot 12^{10} \cdot 20^{10},$$远远超出了计算机可以处理的任何事情。 

这个问题仍然很容易的原因是我们实际上并不关心哪个掷骰序列产生了总和。 我们只需要获得每个总数的方法数量。 由于最多有 451 个不同的总和，因此当我们将骰子一一相加时，我们可以重复更新总和的分布。 

假设我们已经知道在处理一些骰子后每个和可以出现多少种方式。 当另一个人死去时$k$边相加，每个现有的总和正好贡献$k$新的金额。 我们只需将其计数分配到这些新总数中即可。 这正是分布的卷积，但只有几百个可能的和，简单的动态编程实现已经足够快了。 

处理完所有骰子后，每个总和的方式数量与其概率成正比，因为每个完整结果的可能性相同。 按这些计数对总和进行排序可直接生成所需的顺序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(\prod s_i)$|$O(\text{number of sums})$| 太慢了 |
 | 最佳|$O(D \times S \times 20)$|$O(S)$| 已接受 |

 这里，$D \le 50$是骰子的数量，$S \le 500$是最大可能的总和。 

## 算法演练

 1. 读取每种模具类型的编号。 
2. 将输入展开为一个列表，其中每个骰子包含一个条目，其中每个条目存储其面数。 例如，一个 d4 和两个 d8 成为列表`[4, 8, 8]`。 
3. 创建一个动态规划数组，其中`dp[x]`是求和的方法数`x`使用到目前为止处理过的骰子。 最初只能求和 0，所以设置`dp[0] = 1`。 
4. 一次处理一颗骰子。 对于每个骰子`k`边，创建一个新数组`ndp`。 
5. 对于每个可达到的总和以及从 1 到每个面值`k`，将当前的路数添加到相应的新总和中。 每一个现有的结果都可以延伸成每个面值的一个结果。 
6. 更换`dp`和`ndp`并继续，直到每个芯片都被处理完毕。 
7. 根据骰子的数量及其面数计算可达到的最小和最大总和。 
8. 按递减顺序对所有可实现的总和进行排序`dp[sum]`。 如果两个计数相等，则任何相对顺序都是可接受的，因此辅助键是无关的。 
9. 按排序顺序输出总和。 

### 为什么它有效

 在处理骰子的任何前缀后，动态编程表精确计算产生每个可能总和的不同掷骰的数量。 这个不变量最初是正确的，因为在不掷任何骰子的情况下只能实现总和 0。 每次更新都会保留不变性，因为之前的每个骰子都独立地延伸到新骰子的每个面，并且每个最终的骰子都被精确计数一次。 当所有骰子都处理完毕后，`dp[s]`等于结果总数，其总和为`s`。 由于每个完整掷骰的可能性均等，因此按这些计数排序与按概率排序完全相同。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t, c, o, d, i = map(int, input().split())

    dice = (
        [4] * t +
        [6] * c +
        [8] * o +
        [12] * d +
        [20] * i
    )

    max_sum = sum(dice)
    dp = [0] * (max_sum + 1)
    dp[0] = 1

    current_max = 0

    for sides in dice:
        ndp = [0] * (max_sum + 1)
        for s in range(current_max + 1):
            if dp[s] == 0:
                continue
            ways = dp[s]
            for face in range(1, sides + 1):
                ndp[s + face] += ways
        dp = ndp
        current_max += sides

    min_sum = len(dice)

    ans = list(range(min_sum, max_sum + 1))
    ans.sort(key=lambda x: dp[x], reverse=True)

    print(*ans)

if __name__ == "__main__":
    solve()
```该解决方案首先将压缩输入扩展为每个芯片的一个列表条目。 这使得每次更新都相同，无论芯片类型如何。 

动态规划数组总是代表处理一定数量的骰子后的分布。 为每个芯片分配一个新的数组，因为每个转换必须仅使用前一阶段的值。 就地更新数组会意外地重用新创建的状态并过量计算许多总和。`current_max`跟踪处理骰子后可达到的最大总和。 仅迭代到该值可以避免扫描未使用的条目。 

Python 整数会自动增长到任意精度，因此即使是最大测试的大量可能的滚动也不会溢出。 

最后，可实现的金额按计数排序。 由于概率的差异仅在于等于结果总数的公分母，因此比较计数就足够了。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(D \times S \times 20)$| 每个骰子最多使用 20 个面来更新每个可达到的总和。 |
 | 空间|$O(S)$| 仅存储当前和下一个分布。 |

 由于最多有 50 个骰子，而最大可能的总和仅为 500，因此该算法在 100 万次转换操作下表现良好。 这很容易满足问题限制。 

## 测试用例```python
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    t, c, o, d, i = map(int, input().split())

    dice = [4] * t + [6] * c + [8] * o + [12] * d + [20] * i
    max_sum = sum(dice)

    dp = [0] * (max_sum + 1)
    dp[0] = 1
    cur = 0

    for sides in dice:
        ndp = [0] * (max_sum + 1)
        for s in range(cur + 1):
            if dp[s]:
                for f in range(1, sides + 1):
                    ndp[s + f] += dp[s]
        dp = ndp
        cur += sides

    mn = len(dice)
    ans = list(range(mn, max_sum + 1))
    ans.sort(key=lambda x: dp[x], reverse=True)
    return " ".join(map(str, ans))

 ## 边缘情况

 考虑输入```
1 0 0 0 0
```动态规划表开始于`dp[0] = 1`。 处理完 d4​​ 后，sums 1 到 4 每个都恰好收到一份贡献。 每个计数都是相同的，因此每个订单都是有效的。 该算法自然会产生相同的频率，无需任何特殊处理。 

现在考虑```
0 0 0 0 1
```d20只有一张。 每个面只贡献一次，因此所有 20 个总和都得到计数 1。按频率排序使所有总和保持平局，符合平局可能以任何顺序出现的规范。 

最后，考虑```
10 10 10 10 10
```最小可达到的和是 50，最大是 500。尽管可能的掷骰总数大得难以想象，但动态规划表仍然只包含 501 个条目。 每个骰子对每个可能的总和最多执行 20 次转换，因此运行时间仅取决于总和的范围而不是单个结果的数量。
