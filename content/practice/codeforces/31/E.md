 ## 解决方案
 ## 问题理解

 我们得到一串`2n`数字。 数字严格从左到右处理。 在每一步中，Homer 或 Marge 都会采用当前最左边的数字并将其附加到自己的号码上。 到最后，两名选手都必须准确地采取`n`数字。 

最终得分是两个构建数字的总和。 我们必须输出一个有效的移动序列，使用`H`和`M`，最大化这个总数。 

关键细节是每个球员号码内的顺序是固定的。 如果荷马在位置上取数字`i1 < i2 < ...`，那么他的号码正是按该顺序排列的那些数字。 玛吉也是如此。 

约束足够小以允许动态编程，但又足够大以至于无法对所有分配进行暴力破解。 自从`n ≤ 18`, 总位数最多为`36`。 对玩家的所有数字分配进行天真的搜索将检查`2^(2n)`的可能性。 在最坏的情况下，这会变成`2^36`，大约680亿个状态，2秒内完全不可行。 

同时，`36 × 36 × 10^18`风格算术完全没问题。 最终数字本身最多可以有 18 位数字，因此需要 64 位整数。 Python 整数会自动处理这个问题。 

如果推理不精确，一些边缘情况很容易处理错误。 

考虑：```
1
09
```如果荷马采取`0`玛吉采取`9`，总计为`0 + 9 = 9`。 

如果荷马采取`9`玛吉采取`0`，总计为`9 + 0 = 9`。 

前导零是合法的，因此我们不能将构造的字符串视为无效数字。 

另一个微妙的情况是：```
2
9090
```总是将当前数字提供给当前值较小的玩家的贪婪策略可能会失败，因为较早的数字更重要。 较早分配的数字比分配较晚的数字会更改更高的小数位。 

一个更重要的场景是：```
2
1234
```如果 Homer 取前两位数字，Marge 取后两位数字，我们得到`12 + 34 = 46`。 

但交替给出：`13 + 24 = 37`每个球员号码中的位置比绝对数字本身更重要。 前面放置的数字贡献更大的 10 次幂。 

## 方法

 蛮力的想法很简单。 对于每个`2n`位置，决定数字是归 Homer 还是 Marge，同时确保两者都准确接收`n`数字。 

一旦分配确定，我们就可以构造两个数字并计算它们的总和。 有效分配的数量为：$$\binom{2n}{n}$$为了`n = 18`， 这是：$$\binom{36}{18} \approx 9 \times 10^9$$即使检查这些状态的一小部分也是不可能的。 

暴力破解在概念上起作用的原因是每个有效序列唯一地确定最终数字。 问题纯粹是组合的爆炸。 

关键的观察是，数字的贡献仅取决于两件事：

 首先，哪个玩家收到它。 

其次，该玩家之后仍将收到多少位数字。 

假设荷马已经采取了`h`位置前的数字`i`。 那么当前数字就变成了`(h+1)`荷马号码的第 - 位数字。 因为荷马的结尾恰好是`n`数字，该数字贡献：$$digit \times 10^{n-h-1}$$未来的决定不会改变这一地位权重。 

这意味着我们可以从左到右处理数字，并使用动态规划来计算 Homer 已经取了多少位数字。 

在位置`i`，玛吉已经自动采取了`i-h`数字。 

所以整个状态由一个参数决定：$$dp[i][h]$$表示处理第一个后可获得的最大总价值`i`数字，荷马已经准确地取了`h`其中。 

从这个状态，我们尝试：

 1. 将下一个数字交给 Homer。 
2. 将下一个数字交给 Marge。 

每个转变都会立即增加一个已知的贡献。 

州总数仅约`36 × 18`，足够小，可以立即计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^(2n)) | O(2^(2n)) | O(2^(2n)) | O(2^(2n)) | 太慢了 |
 | 最佳DP | O(n²) | O(n²) | 已接受 |

 ## 算法演练

 1. 阅读`n`和数字字符串`s`。 
2. 预先计算 10 的幂`10^0`最多`10^18`。 

这些权力决定了每个数字的位置贡献。 

1. 定义`dp[i][h]`作为处理第一个后可实现的最大总价值`i`数字，荷马已经准确地取了`h`数字。 

由于玛吉自动采取了`i-h`数字，我们不需要另一个维度。 

1.初始化：```
dp[0][0] = 0
```所有其他状态均以负无穷开始。 

1. 从左到右处理数字。 

假设我们在位置`i`，荷马已经采取了`h`数字。 

让：```
m = i - h
```是 Marge 已经占用的位数。 

1. 尝试将当前数字分配给 Homer。 

这只有在以下情况下才有可能：`h < n`。 

数字变成荷马的`(h+1)`第 - 位，因此其十进制重量为：$$10^{n-h-1}$$将此贡献和转换添加到：```
dp[i+1][h+1]
```1. 尝试将当前数字分配给 Marge。 

这只有在以下情况下才有可能：`m < n`。 

该数字成为玛吉的`(m+1)`第 - 位，所以它的权重是：$$10^{n-m-1}$$将此贡献和转换添加到：```
dp[i+1][h]
```1. 存储父级信息以供重建。 

对于每一个改进的过渡，请记住：

 1. 先前的状态。 
2.我们是否选择`H`或者`M`。 
3. 处理完所有数字后，答案存储在：```
dp[2n][n]
```1. 通过向后遍历父指针来重建移动序列。 

最后反转收集到的字符。 

### 为什么它有效

 一旦我们知道哪个玩家接收到它以及它占据该玩家号码中的哪个位置，每个数字就会独立贡献。 

当从左到右处理数字时，Homer 数字中的位置完全取决于 Homer 已经取了多少位数字。 玛吉也是如此。 

因此，一个国家未来的每一个结果仅取决于：

 1. 已处理了多少位数字。 
2. 荷马拿走了多少。 

DP 对每个有效分配进行一次探索，并计算每个状态的最佳可实现总数。 由于转换添加了当前数字的精确小数贡献，因此最终值等于两个构造数字的真实总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = -(10**30)

def solve():
    n = int(input())
    s = input().strip()

    total = 2 * n

    pow10 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow10[i] = pow10[i - 1] * 10

    dp = [[INF] * (n + 1) for _ in range(total + 1)]
    parent = [[None] * (n + 1) for _ in range(total + 1)]

    dp[0][0] = 0

    for i in range(total):
        digit = int(s[i])

        for h in range(n + 1):
            if dp[i][h] == INF:
                continue

            m = i - h

            # Give digit to Homer
            if h < n:
                add = digit * pow10[n - h - 1]
                val = dp[i][h] + add

                if val > dp[i + 1][h + 1]:
                    dp[i + 1][h + 1] = val
                    parent[i + 1][h + 1] = (i, h, 'H')

            # Give digit to Marge
            if m < n:
                add = digit * pow10[n - m - 1]
                val = dp[i][h] + add

                if val > dp[i + 1][h]:
                    dp[i + 1][h] = val
                    parent[i + 1][h] = (i, h, 'M')

    ans = []

    i = total
    h = n

    while i > 0:
        pi, ph, ch = parent[i][h]
        ans.append(ch)
        i, h = pi, ph

    ans.reverse()

    print("".join(ans))

solve()
```DP 表存储每个前缀长度和分配给 Homer 的每个可能位数的最佳可实现总数。 

转换逻辑是解决方案的核心。 当分配一个数字时，我们立即知道它的确切位置权重。 例如，如果荷马已经采取了`h`数字，则当前数字成为其数字中的下一个数字并贡献：```
digit × 10^(n-h-1)
```以后的任何决定都不能改变这一贡献。 

父表是必要的，因为问题要求的是移动顺序，而不仅仅是最大分数。 每个家长条目记录：

 1. 先前的状态。 
2. 哪个玩家收到了这个数字。 

一个微妙的细节是 Marge 位数的计算：```
m = i - h
```这之所以有效，是因为正是`i`数字已被处理，并且`h`其中一些人去了荷马。 

另一个容易犯的错误是忘记前导零是有效的。 DP 自然地处理它们，因为数字纯粹被视为位置贡献。 

值范围可以超过 32 位整数。 Python 整数自动避免溢出。

 ## 边缘情况

 考虑输入：```
1
09
```在第一个数字处，分配`0`任一玩家贡献：```
0 × 10^0 = 0
```第二位数字贡献`9`。 

两项作业产生相同的总分。 DP 自然地处理这个问题，因为前导零被视为具有位置权重的普通数字。 

现在考虑：```
2
9090
```粗心的贪婪策略可能会试图平衡两个玩家当前的数值。 但这失败了，因为小数点位置比当前总数更重要。 

相反，DP 会评估确切的贡献：

 | 数字| 如果第一位数字则持仓权重 | 如果第二位数字则持仓权重 |
 | --- | --- | --- |
 | 9 | 10 | 10 1 |

 分配第一个`9`early is always much more valuable.

 最后，考虑：```
2
1000
```如果荷马领先`1`，其贡献为：```
1 × 10 = 10
```如果`1`成为某人的第二位数字，其贡献下降到`1`。 

DP 通过指数自动捕获这一点：```
pow10[n - h - 1]
```它精确地跟踪该球员的号码中剩余的位置。
