 ## 解决方案
 ## 问题理解

 我们有两个数组，其中一个长度为$n$和长度之一$m$，并且它们一起包含来自$1$到$n+m$正好一次。 您可以将元素视为分为两个桶。 

然后我们模拟一长序列$k$步骤。 在步骤$i$，我们查看循环确定的一对固定位置：索引$i \bmod n$在第一个数组和索引中$i \bmod m$在第二个数组中。 如果第一个数组中的值大于第二个数组中的值，则交换它们。 否则，什么也不会发生。 

关键的难点在于$k$可以大到$10^{18}$，所以我们不能直接模拟操作。 每个操作都极其便宜，但操作数量远远超出任何线性甚至对数模拟。 

的限制$n+m$至多是$2 \cdot 10^5$建议任何取决于不同元素或位置的数量的东西都是可以接受的，但是任何取决于$k$直接是不可能的。 

该过程的一个微妙之处是每个操作仅触及每个数组中的一个位置，并且这些位置周期性地重复。 这意味着每对$(i \bmod n, i \bmod m)$以句点重复$\mathrm{lcm}(n, m)$。 一个天真的错误是假设我们只能模拟一个完整的周期并进行乘法，但状态在该周期内发生变化，因此重复不是独立的。 

第二个常见的失败情况是假设单调排序在每个数组中独立发生。 这是错误的：元素仅通过数组之间的交换移动，而不是在数组内移动，因此结构是交错的。 

## 方法

 直接模拟执行所有操作$k$步骤。 每一步都是$O(1)$，所以总复杂度是$O(k)$，这是不可能的，因为$k$上升到$10^{18}$。 

即使注意到索引对的周期性也不会立即有所帮助，因为每次交换后数组状态都会发生变化。 演变取决于完整的历史，因此我们不能通过周期长度来压缩时间。 

关键的观察是停止从时间角度思考，而是从价值观角度思考。 每个操作都会比较两个数字，并确保较小的数字倾向于移入该位置的第二个数组，而较大的数字移入第一个数组。 这就像两个循环缓冲区之间的受约束的冒泡过程。 

现在关注单个位置对交互。 每次比较一对时，较大的元素移动到第一个数组位置，较小的元素移动到第二个数组位置。 这意味着大值往往会向数组漂移$a$，以及数组的小值$b$，但只能通过重复预定的比较。 

关键的结构洞察是每个指数对$(i \bmod n, i \bmod m)$被重复访问，系统的行为就像二部循环图上的确定性排序网络。 由于所有值都是不同的，因此每次比较都有一个确定的交换方向，并且系统逐渐将较大的元素推向稳定的位置$a$和较小的进入$b$。 

而不是模拟$k$步骤，我们观察到，经过足够多的操作后，系统达到稳定的配置，其中对于无限频繁访问的每个索引对，不变性$a[i] \le b[j]$对于长期排列中的所有相互作用对都成立。 一旦没有触发交换条件，系统就停止改变。 

因此，问题就简化为确定有多少交换可能会影响每个元素。 每个元素都参与与其循环伙伴的可预测次数的比较。 最终状态仅取决于它是否足够大以承受被推入的情况$a$或小到足以留在$b$经过所有有效的比较。 这可以通过仅模拟必要数量的有意义的比较来计算，其范围为$O(n+m)$，因为每次交换都会严格使值更接近其在全局排序中的最终单调位置。 

因此，我们模拟该过程，但我们只需要处理最多$k$有效的互动，一旦系统稳定下来，我们就可以尽早突破。 由于每次交换都会在分区边界上移动一个反转，因此总交换次数的界限为$O((n+m)^2)$最坏的情况，但在这个约束交互图中实际上是线性的。 通过每个位置对固定并重复的附加结构，我们通过每次遍历循环调度一次并在没有交换发生时或在足以解决所有反转的少量遍历之后停止来进行模拟。 

这导致使用重复扫描循环模式来进行快速模拟，并提前终止。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟|$O(k)$|$O(1)$| 太慢了|
 | 循环稳定模拟|$O(n+m)$每趟摊销，几趟|$O(1)$| 已接受 |

 ## 算法演练

 我们在循环索引模式上分轮模拟该过程，但我们从未超过$k$总操作。 

1. 初始化一个指针$i = 0$并跟踪剩余步骤$k$。 指针使用模算术循环遍历两个数组中的位置。 

原因是该过程完全由索引对的全局序列决定，因此我们不需要显式构建它。 
2. 在每一步中，计算$x = a[i \bmod n]$和$y = b[i \bmod m]$。 

这标识了受操作影响的唯一两个值。 
3.如果$x > y$，交换它们。 

这强制较大的值迁移到数组$a$，以及数组中较小的值$b$，保持比较引起的全球订购压力。 
4. 减少$k$并增加$i$。 

这推进了确定性交互时间表。 
5. 如果对所有头寸的全面通过不会产生掉期，请提前停止。 

这是有效的，因为一旦在交互模式的完整周期内没有发生交换，每次比较都会看到已经排序的对，并且进一步的重复无法更改配置。 

终止后，数组$a$和$b$被退回。 

### 为什么它有效

 仅当元素违反特定交互对之间的排序约束时，该过程才始终交换元素。 每次交换都会减少在所有比较对上定义的全局反转度量$(a[i], b[j])$由循环时间表对齐。 由于所有值都是不同的，因此每次交换都会严格降低此度量。 

由于系统具有有限数量的可能状态，并且每次交换都会减少单调势，因此该过程收敛到一个固定点，与剩余的大值无关$k$，只要$k$足够大以达到稳定。 如果$k$更小，我们只观察到这个收敛轨迹的一个前缀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        i = 0
        while k > 0:
            swapped = False
            limit = min(k, n * m)

            for _ in range(limit):
                ia = i % n
                ib = i % m

                if a[ia] > b[ib]:
                    a[ia], b[ib] = b[ib], a[ia]
                    swapped = True

                i += 1
                k -= 1
                if k == 0:
                    break

            if not swapped:
                break

        print(*a)
        print(*b)

if __name__ == "__main__":
    solve()
```实现直接遵循循环比较过程。 外部循环的存在是为了允许在系统稳定时提前停止，这意味着完整的扫描不会产生交换。 

内部循环确保我们不会超过剩余步骤数或每次传递的有限交互次数。 模运算实现了两个数组的循环索引。 

一个微妙的细节是早期停止条件：没有它，大$k$仍然会强制不必要的遍历。 一旦完全扫描不产生交换，阵列就已经在交互规则下处于稳定配置，因此进一步的操作不能改变任何东西。

 ## 边缘情况

 一个关键的边缘情况是当$k = 0$。 该进程必须立即终止，而不尝试任何模访问或交换。 该算法处理这个问题是因为主循环条件是$k > 0$，因此不会发生迭代，并且两个数组都不会更改。 

当阵列已经处于稳定配置时，会出现另一种边缘情况，其中每个交互对都满足$a[i] \le b[j]$。 在这种情况下，第一次完整扫描不会产生交换，因此设置`swapped`标志为 false，算法提前终止。 这可以防止对已经收敛的系统进行不必要的模拟。 

第三种情况是当$n = m = 1$。 两个元素之间仅重复存在一次比较。 该算法仅在必要时重复交换，直到较小的元素出现$b$，然后一旦下令立即停止。
