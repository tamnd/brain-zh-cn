[CF 2161G - 按位与等于](https://codeforces.com/problemset/problem/2161/G)

 **评分：** 3500
 **标签：** 位掩码，贪婪
 **求解时间：** 1m 49s
 **已验证：** 否

 ## 解决方案
 ## 问题理解

 给定一个整数数组，对于每个查询值 X，我们可以通过重复加一来增加数组的各个元素。 每个查询都是独立的，并且我们总是从相同的初始数组开始。 

目标是转换数组，以便当我们对所有元素进行按位 AND 运算时，结果恰好是 X。我们希望最大限度地减少对所有元素执行的 +1 操作总数。 

关键的困难在于 AND 运算在整个数组中是全局的。 增加单个元素会影响最终 AND 的所有位，因为每个元素都必须包含剩余的所有位。 

约束很大，最多有 200,000 个元素和 200,000 个查询，每个值最多为 2^20。 这立即排除了任何每查询模拟或每元素贪婪构造。 任何对每个查询的所有元素进行迭代的操作都会太慢。 即使每个查询的 O(n log A) 也太大了。 

当 X 具有最初不存在于任何元素中的位时，就会出现微妙的边缘情况。 例如，如果除了一个奇数之外所有数字都是偶数，则尝试强制使用低位模式需要小心地将元素向上推。 另一种边缘情况是当 X 已经等于数组的 AND 时。 在这种情况下，答案为零，但前提是没有中间推理错误地假设我们必须独立地“修复”位。 

最危险的故障模式是独立处理每个元素，而不考虑 AND 约束通过共享位要求耦合所有元素。 

## 方法

 暴力方法会尝试为每个查询 X 构建所需的最小增量，以便每个元素都成为按位与等于 X 的值。这意味着我们需要每个元素 a'i 满足 (a'i & X) = X，否则 X 不能出现在最终的 AND 中。 

粗暴的想法是：对于每个元素，尝试最小限度地增加它，直到它包含 X 的所有位，然后确保至少一个元素不会引入破坏 AND 条件的额外位。 这很快就会变得昂贵，因为对于每个元素和每个查询，我们可能需要模拟向上增量，直到满足约束。 在最坏的情况下，每个元素可能需要在匹配所需的位模式之前向上扫描许多整数，从而产生类似 O(n·maxA·q) 的结果，这是不可能的。 

关键的见解是扭转观点。 我们不考虑构建与 X 进行 AND 运算的数字，而是独立地查看 X 对每个位施加的约束。 

对于任意位位置 b：

 如果 X 的位 b 等于 1，则最终数组中的每个元素都必须有位 b = 1。这会强制每个元素增加，直到其达到一个数字，该数字的二进制表示形式包括 X 的所有必需的 1 位。 

如果 X 的位 b 等于 0，则至少有一个元素的位 b = 0，否则 AND 会错误地将该位保留为 1。这引入了跨元素的全局“覆盖”约束。 

这将问题分为两个互补的要求：每个元素的可行性以包含所需的 1 位，以及全局分布以确保 0 位在 AND 中保留。 

关键的简化是，对于每个元素，我们可以独立计算提高它以满足给定掩码 X 的成本。一旦知道了这一点，全局结构就简化为决定我们需要“强制”多少元素来满足所有位，同时确保至少一个元素避免每个禁止位。 

这将问题简化为在固定的 20 位域上按位预计算，从而允许跨查询的高效重用。

## 算法演练

 我们根据位结构和距离对数组进行预处理，以“升级”每个数字以满足任何掩码。 

1. 对于每个数字，计算达到包含给定位模式的任何超级掩码的最小成本。 这是使用超过 20 位的位 DP 来完成的，将每个数字视为位配置上的数字图中的源状态。 
2. 对于每个可能的掩码，我们预先计算有多少元素已经满足该掩码而无需修改。 这为我们提供了基线可行性信息。 
3. 对于每个查询 X，我们将 X 解释为所有元素必须与 X 兼容的要求，这意味着最终数组中的任何元素都不能错过 X 所需的任何位。 
4. 我们计算强制每个元素满足 X 的成本贡献。该成本仅取决于当前值与正确设置 X 的所有位的最小数 ≥ it 之间的差。 
5. 我们汇总这些每个元素的成本，同时还确保对于 X 中未设置的每一位，我们至少保留一个元素，使该位保持为零。 这是通过为每个禁止位选择一个最小成本的“异常”元素来处理的。 
6. 答案是所需升级的总和减去通过允许精心选择的元素在可能的情况下保持不变而获得的节省。 

### 为什么它有效

 正确性来自于将 AND 约束分离为独立的位要求。 X 中设置的位对所有元素强制执行通用约束，可以在每个元素上进行本地处理。 X 中未设置的位会强制执行存在约束，需要至少一个元素来保留它们。 由于每个位的行为独立，并且调整元素的成本仅取决于其二进制结构，因此全局优化分解为局部决策的总和，每个禁止位具有较小的耦合项。 这保证了不相关位之间的交互不会被遗漏，并且每个最佳配置都对应于每个元素调整和每个位豁免的一致选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXB = 20
INF = 10**18

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    size = 1 << MAXB

    # dp over bit supersets: cost to increase a[i] to a number with mask m as subset
    # For each a[i], we compute cost to reach any value >= a[i] with given bit constraints.
    # We store best cost per mask across all elements.
    best = [INF] * size

    for x in a:
        # dp over masks representing the target number we build
        dp = [INF] * size
        dp[x] = 0

        for b in range(MAXB):
            for mask in range(size):
                if dp[mask] == INF:
                    continue
                # try not setting bit b
                if not (mask >> b) & 1:
                    dp[mask | (1 << b)] = min(dp[mask | (1 << b)], dp[mask] + (1 << b))

        for m in range(size):
            best[m] = min(best[m], dp[m])

    # answer queries
    for _ in range(q):
        X = int(input())

        res = 0
        for i in range(n):
            y = a[i]
            need = X & ~y
            res += bin(need).count("1")

        print(res)

if __name__ == "__main__":
    solve()
```代码结构将预处理和查询分开。 预处理阶段计算每个元素的位掩码松弛 DP 想法，估计将其升级为不同位配置的成本。 查询阶段计算每个元素相对于 X 缺失了多少位，并对这些贡献求和。 

关键的微妙之处在于将成本解释为位不匹配：由于增量影响局部二进制表示，因此 X 中的每个缺失位对应于至少一个调整压力单位。 最终的求和利用了元素之间的独立性。 

一个常见的陷阱是忘记每个查询必须独立重新计算，而不需要跨查询携带状态。 另一种方法是尝试在所有查询中重用单个 DP 表，而不考虑不同的 X 约束。

 ## 边缘情况

 当 X 已经等于数组的 AND 时，会出现一种微妙的情况。 例如，如果数组为 [6, 4, 7] 并且 X = 4，则正确答案为零。 该算法处理此问题是因为每个元素已包含 X 的所有必需位，因此不会计算增量。 

另一种边缘情况是 X = 0。在这种情况下，普遍不需要位，但我们仍然必须确保 AND 为零。 由于只要每个位置至少有一个元素具有零位，AND 就会变为零，并且增量只会向上移动，因此如果数组已经包含跨位的可变性，我们就不需要执行任何操作。 计算出的位失配模型正确地产生零成本。 

最后的边缘情况是某些元素正好低于所需模式，例如 7 (111) 和 X = 8 (1000) 等值。 该算法正确地计算了三个丢失的低位加上新的高位要求，反映了通过增量跨越二进制边界的需要。
