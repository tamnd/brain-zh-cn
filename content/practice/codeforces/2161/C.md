 ## 解决方案
 ## 问题理解

 我们被要求在商店中最大化奖励积分，因为每次购买都有可能提高我们的忠诚度水平。 每件商品的价格介于 1 和某个忠诚度系数之间$X$。 最初，我们的忠诚度水平计算为我们总支出的整数除法$S$经过$X$。 每当购买商品提高忠诚度水平时，我们都会获得相当于该商品价格的奖励积分。 购买顺序很重要，因为以不同顺序购买相同的商品会产生不同数量的忠诚度级别增加。 

输入由多个测试用例组成，每个测试用例提供商品数量、忠诚度因子和商品价格列表。 输出是可实现的最大总奖励积分以及达到该最大值的项目示例顺序。 每个测试用例的项目数量可以高达$10^5$，所有测试用例的总和也达到$10^5$，所以我们需要一种有效的方法。 

一个天真的解决方案会尝试所有$n!$项目的排列以找到最大化奖励积分的序列。 即使是为了$n = 10$，这已经不切实际了，所以我们需要一种更聪明的方法。 边缘情况包括所有项目等于$X$，保证每次购买或所有物品小于$X$这样单个项目无法立即触发忠诚度增加。 

另一个微妙的情况是当较小项目的总和刚刚达到下一个倍数时$X$- 在这里，算法必须仔细选择首先购买哪些商品，以触发尽可能多的忠诚度水平提高。 

## 方法

 暴力方法是生成项目的所有排列并模拟每个序列的奖金计算。 原则上这是正确的，因为它显式地检查每个可能的顺序，但时间复杂度是$O(n!)$，这对于$n \sim 10^5$。 即使对于 10 个元素的小数组，这也已经导致超过 300 万种排列。 

优化的关键观察是我们只关心达到$X$高效。 当累积总和超过下一个倍数时，就会产生奖励积分$X$。 这表明了一种贪婪的方法：我们希望在达到目标的倍数之前花费尽可能少的钱$X$以便下一个项目触发忠诚度增加。 如果我们按升序对项目进行排序，我们可以确保较小的项目首先累积，使累积总数更接近下一个倍数，而不会出现超调。 然后可以使用较大的物品来触发忠诚度增加。 

换句话说，通过按非递减顺序对项目进行排序，每个项目要么太小而无法单独触发忠诚度增加，要么是使总和超过多个的最小项目$X$。 这种排序最大化了忠诚度级别增量的数量，这正是我们获得奖励积分的时候。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，读取项目数$n$和忠诚度因素$X$。 
2. 阅读商品价格表$a_1, a_2, ..., a_n$。 
3. 按升序对商品价格进行排序。 这确保我们首先使用较小的项目来达到$X$高效。 
4. 初始化累计和$S = 0$和奖励积分$B = 0$。 
5. 迭代已排序的项目：

 - 将当前商品价格添加到$S$。 
- 将之前的忠诚度水平计算为$(S - a_i) // X$。 
- 将新的忠诚度水平计算为$S // X$。 
- 如果新的忠诚度级别超过之前的忠诚度级别，则将当前商品价格添加到$B$。 
6.处理完所有项目后，输出$B$和排序后的序列。 

为什么它有效：排序确保我们首先积累较小的贡献，因此每次我们跨越多个$X$，负责穿过它的项在其余项中尽可能大。 这可以最大化从每次忠诚度提升中获得的奖励积分。 不变的是每一步，$S$是迄今为止所有购买商品的总和，并跨越$X$准确地触发当前项目的奖励。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, X = map(int, input().split())
        prices = list(map(int, input().split()))
        prices.sort()
        bonus = 0
        S = 0
        for price in prices:
            prev_loyalty = S // X
            S += price
            new_loyalty = S // X
            if new_loyalty > prev_loyalty:
                bonus += price
        print(bonus)
        print(' '.join(map(str, prices)))

if __name__ == "__main__":
    solve()
```该代码使用快速 I/O 有效地读取多个测试用例。 排序对于最大化奖励积分至关重要，累积总和逻辑可确保我们正确检测忠诚度水平何时增加。 需要注意分别计算每个项目的先前和新的忠诚度级别，以避免相差一的错误。
