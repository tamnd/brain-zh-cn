 ## 解决方案
 ## 问题理解

 输入描述了几个矩形数字网格。 每个网格在概念上都被分成同心“环”或层，从外边界开始向内移动。 如果沿着其边界顺时针行走，每一层都会形成一个闭合循环。 

对于每个这样的循环，我们想象以精确的遍历顺序读取数字。 在网格的所有层中，我们被要求计算连续序列“1543”在这些循环字符串中出现的次数。 

一个关键细节是每一层都是独立的：首先读取外环，然后将其删除，下一个内部矩形成为新的外环。 总答案是所有层中出现次数的总和。 

这些约束强制每个测试用例采用线性或近线性解决方案。 所有网格中的单元总数最多为 10^6，因此任何处理每个单元恒定次数的方法都是可以接受的。 在最坏的情况下，任何重复重新计算层字符串或对每层边界执行重复扫描的操作都会面临二次行为的风险，特别是对于像 1000 x 1000 这样大约有 500 层的网格。 

一种简单的方法是将每一层显式提取到一个字符串中，然后运行“1543”的子字符串搜索。 这看起来已经很安全，但是如果我们重复地切片或重建每层的中间列表，那么提取的完成方式就会出现微妙的低效率。 在 Python 中，层构建过程中不小心的串联可能会显着降低性能。 

第二个更危险的陷阱是忘记层是循环的。 图案“1543”可以环绕线性化层表示的边界。 例如，如果一个层以“1”结尾并以“543”开头，则该模式存在，但对展开序列的直接子字符串检查将错过它，除非我们显式处理环绕。 

边缘情况示例：

 网格层遍历：`... 5 4 3 1`如果我们只检查线性子串的出现，如果序列实际上是循环的，我们将错过“1543”的出现。 

正确的处理需要将每一层视为循环或通过将长度为 3 的前缀连接到末尾来模拟环绕。 

## 方法

 暴力破解的想法很简单：对于每一层，将其完整的顺时针遍历提取到数字列表中，然后扫描它是否出现“1543”。 如果我们独立对待每一层并显式构建其字符串，则每层的总工作量与其周长成正比。 对所有层求和，每个单元都属于一层，因此单独提取总体上的复杂度为 O(nm)。 

问题在于我们如何搜索模式。 每层的简单字符串搜索在层大小上仍然是线性的，这很好。 如果我们低效地重复重建层或在循环内使用重复的切片操作，就会出现真正的低效率。 这可能会降低常数的质量，甚至引入隐藏的二次行为。 

关键的观察是，在层遍历中，我们不需要任何超出局部邻接性的东西。 我们可以动态模拟遍历并维护最后四位数字的滚动窗口。 这完全消除了构建完整字符串的需要。 每个单元仅被访问一次，并且每次更新的时间复杂度为 O(1)。 

我们还通过将每一层视为一个循环来自然地处理循环：完成遍历后，必须将最后三位数字与开头进行检查。 循环序列上的滚动哈希窗口干净地解决了这个问题。 

因此，最佳解决方案变为每层边界单次通过，保持长度为四的滑动窗口。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(纳米) | O(纳米) | 如果重复构造实现太慢 |
 | 最佳 | O(纳米) | 每层额外 O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 通过从外向内剥离基质来识别层。 每个层由其顶行、右列、底行和左列边界定义。 
2. 对于每一层，按顺时针顺序遍历其边界，产生数字流。 
3. 维护本次遍历中看到的最后四位数字的滚动缓冲区。 
4. 当缓冲区达到长度 4 时，将其与序列“1543”进行比较。 如果匹配，则增加答案。 
5、由于遍历是循环的，所以遍历完一层后，取该层的前三位，逻辑上继续下去，模拟环绕检查。 
6. 继续，直到处理完所有层。 

关键思想是我们永远不会显式地构建层的完整字符串； 我们仅模拟沿边界的运动并检查局部模式。 

### 为什么它有效

 层中任何出现的“1543”都必须对应于该层循环遍历中的四个连续位置。 通过在遍历顺序上维护一个滑动窗口，每个可能的起始位置都会被检查一次。 循环性质是通过在概念上扩展遍历来处理的，确保跨越结束和开始之间边界的模式也被计算在内。 由于每一层都是不相交且完全覆盖的，因此不会遗漏或重复计算任何事件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

TARGET = "1543"

def count_layer(mat, top, bottom, left, right):
    seq = []

    # top row
    for j in range(left, right + 1):
        seq.append(mat[top][j])

    # right column
    for i in range(top + 1, bottom + 1):
        seq.append(mat[i][right])

    # bottom row
    for j in range(right - 1, left - 1, -1):
        seq.append(mat[bottom][j])

    # left column
    for i in range(bottom - 1, top, -1):
        seq.append(mat[i][left])

    if len(seq) < 4:
        return 0

    # simulate cyclic behavior by extending first 3 chars
    ext = seq + seq[:3]

    count = 0
    window = []

    for ch in ext:
        window.append(ch)
        if len(window) > 4:
            window.pop(0)
        if len(window) == 4 and "".join(window) == TARGET:
            count += 1

    return count

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        mat = [input().strip() for _ in range(n)]

        top, bottom = 0, n - 1
        left, right = 0, m - 1

        ans = 0

        while top <= bottom and left <= right:
            ans += count_layer(mat, top, bottom, left, right)
            top += 1
            bottom -= 1
            left += 1
            right -= 1

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案按顺时针顺序提取每个层边界，然后独立处理。 这`count_layer`函数负责展平单个环并检查目标模式的出现，包括通过将前三个字符附加到末尾来进行环绕处理。 

分层剥离在`solve()`确保每个单元恰好属于一个环，并且边界正确地向内收缩。

 ## 边缘情况

 一个小但重要的情况是最小的 2x2 网格，其中唯一的层形成长度为 4 的循环。算法将其转换为序列并附加前三个字符，确保环绕检测仍然有效。 如果没有这个扩展，像“1543”这样从遍历的最后一个单元格开始的模式就会被错过。 

另一种情况是薄矩形环，例如2米。 在这里，遍历退化为没有垂直边的两行。 该构造仍然产生有效的循环序列，因为右列循环和左列循环变空，并且算法自然回落到水平循环。
