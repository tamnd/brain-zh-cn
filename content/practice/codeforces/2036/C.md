 ## 解决方案
 ## 问题理解

 我们得到一个随时间变化的二进制字符串。 每个查询都会更新一个位置，将该字符翻转为 0 或 1。每次更新后，我们必须回答一个非常具体的问题：当前字符串是否包含模式“1100”作为任何地方的连续块？ 

因此，每个操作都会突变一个字符，每次突变后，我们都会概念性地扫描长度为 4 的任何子字符串是否等于 1100。 

这些约束立即排除每个查询对整个字符串的任何重新计算。 所有字符串的总长度最多为2×10^5，更新的总数也最多为2×10^5。 每次查询对字符串的完整扫描将是 O(nq)，可以达到 4×10^10 次操作，远远超出了可行的限制。 如果天真地完成，即使每次更新重新计算所有子字符串的滚动哈希仍然会太慢。 

关键的观察结果是每次更新仅影响一个非常小的本地社区。 单个字符翻转无法创建或销毁远离更新索引的“1100”的出现。 它仅影响与更新位置重叠的子字符串。 

微妙的边缘情况来自边界处理。 如果字符串长度小于 4，则答案始终为“否”。 另一种情况是，当更新在小区域内重复切换字符时，可能会创建和删除重叠的出现，例如：```
11100
```这里“1100”从位置 2 开始出现。一种仅检查更新索引周围的一个窗口但错过相邻窗口的简单方法会在重叠模式上失败，例如：```
111100
```其中包含从位置 2 和 3 开始的“1100”。 

因此，我们必须确保正确维护所有可能的长度为 4 的窗口。 

## 方法

 一种简单的方法是在每次更新后通过扫描长度为 4 的所有子字符串来重新计算“1100”是否存在。这是正确的，因为我们显式检查每个可能的窗口，但每次查询的成本为 O(n)。 对于最多 2×10^5 的查询，这太慢了。 

重要的结构见解是，只有包含更新索引的长度为 4 的子字符串才能更改其值。 每次更新最多只能影响 4 个候选子串：从 i−3、i−2、i−1 和 i 开始的子串。 这减少了从全局重新计算到本地维护的问题。 

我们维护一个全局计数器，记录当前存在“1100”的出现次数。 最初我们在 O(n) 内计算一次。 对于每个查询，我们删除所有受影响窗口的贡献，应用更新，然后重新添加贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nq) | O(1) | O(1) | 太慢了|
 | 最佳（本地窗口更新）| O(n + q) | O(n) | 已接受 |

 ## 算法演练

 我们将字符串视为数组，并维护 i 满足 s[i:i+4] = "1100" 的索引数量的运行计数。 

1. 初始化字符串并计算有多少个长度为 4 的子字符串等于“1100”。 这给出了初始答案状态。 
2. 对于位置 i 处的每次更新，首先删除可能受该索引影响的所有子串的贡献。 这些是起始位置 i−3、i−2、i−1 和 i。 
3. 通过将 s[i] 设置为新值来应用更新。 
4. 更新后重新计算相同四个候选起始职位的贡献。 
5.处理后，如果计数大于零，则输出YES，否则输出NO。 

我们在更新之前删除的原因是为了避免重复计算包含旧字符值的陈旧子字符串。 

### 为什么它有效

 “1100”的每次出现完全由四个连续字符确定。 更改一个字符只能影响包含该字符的子字符串。 任何完全超出范围 [i−3, i+3] 的子串都保持不变，因此它对计数的贡献是不变的。 通过限制对可能受影响的窗口的恒定大小集的更新，我们保留了精确的全局计数，而无需扫描整个字符串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def check(s, i):
    if i < 0 or i + 3 >= len(s):
        return False
    return s[i] == '1' and s[i+1] == '1' and s[i+2] == '0' and s[i+3] == '0'

t = int(input())
for _ in range(t):
    s = list(input().strip())
    q = int(input())

    n = len(s)
    cnt = 0

    for i in range(n - 3):
        if s[i:i+4] == ['1', '1', '0', '0']:
            cnt += 1

    for _ in range(q):
        i, v = input().split()
        i = int(i) - 1
        v = v

        for j in range(i - 3, i + 1):
            if check(s, j):
                cnt -= 1

        s[i] = v

        for j in range(i - 3, i + 1):
            if check(s, j):
                cnt += 1

        if cnt > 0:
            print("YES")
        else:
            print("NO")
```该实现将字符串保留为列表以进行有效更新。 辅助检查函数安全地验证从索引 j 开始的窗口是否形成“1100”，超出范围时返回 False。 每个查询在更新前后最多处理四个窗口，确保每个操作持续工作。 

一个常见的错误是忘记在应用更新之前减去旧的贡献。 当窗口从匹配转换为不匹配时，这会导致计数膨胀，反之亦然。 

另一个微妙的点是确保在检查字符串边缘附近的窗口时遵守索引边界。

 ## 边缘情况

 长度小于 4 的短字符串永远不会包含“1100”。 该算法自然会处理这个问题，因为初始循环仅运行到 n−3，这是负数，因此不会计算任何匹配项，并且所有检查都会安全地返回 false。 

由于检查函数中的边界裁剪，字符串开头或末尾的更新仅影响少于四个窗口。 例如，如果 i = 1，我们只考虑从索引 -2 到 1 开始的窗口，并且所有无效索引都将被忽略。 

由于每个窗口都是独立处理的，因此可以正确处理重叠事件。 即使两次出现共享字符，每次查询也会单独计数并在减法和加法过程中一致更新。
