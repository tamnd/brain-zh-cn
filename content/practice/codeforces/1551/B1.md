 ## 解决方案
 ## 问题理解

 我们得到一个由小写拉丁字母组成的字符串。 我们想要选择它的一些位置，并用三个规则为每个选定的位置分配两种颜色（红色或绿色）之一。 

首先，每个选定的位置都只有一种颜色，而某些位置可能保持未绘制。 其次，在每种颜色中，所有选定的字符必须成对不同，因此红色字母不能出现两次，绿色字母不能出现两次。 第三，红色位置的数量必须等于绿色位置的数量。 最后，在所有有效的方法中，我们希望最大化绘制的位置数量，任务是输出最佳排列中红色位置的数量。 

由于红色和绿色的大小相等，因此最大化绘制的字符相当于最大化该值的两倍，因此我们实际上是在两个不相交的不同字母集之间寻找最大可能的平衡配对。 

字符串长度最多为 50，并且有多达 1000 个测试用例，因此任何直接尝试字符串结构上的所有子集或分配的解决方案如果超出组合推理，就已经存在风险。 然而，字母表大小只有 26 个，这是关键的结构限制。 

天真的解释可能会尝试独立分配每个出现的字符，但这会立即打破“每种颜色不同”的规则。 另一种幼稚的方法可能会尝试位置和颜色的所有子集，但这会大致爆炸$3^n$，即使对于$n = 50$。 

一个微妙的边缘情况是一个字母多次出现。 例如，在`"xxxxxx"`，我们不能使用多个`'x'`一个是红色，一个是绿色，所以整个多重性没有帮助。 另一个边缘情况是一串不同的字符，例如`"abcdef"`，其中每个角色都可用，但平衡迫使我们将它们平均分配，因此我们最多只能使用一半。 

真正的限制不是位置而是不同的字母。 

## 方法

 考虑这个问题的强力方法是为每个位置分配三种状态之一：红色、绿色或未使用，然后检查有效性。 对于每个作业，我们验证每个颜色类别不包含重复的字母并且大小匹配。 这探讨了$3^n$状态，甚至与$n = 50$，这远远超出了可行性，因为它达到了大约$10^{23}$配置。 

解锁解决方案的结构是停止根据位置思考，而是根据不同的角色思考。 每个字母最多贡献一个可用的红色插槽和一个可用的绿色插槽，无论出现多少次。 因此，每个字母都可以被压缩为 0、1 或 2 个可用分配的容量，每种颜色一个。 

如果一个字母至少出现两次，则它可以支持两种颜色。 如果出现一次，则只能支持一种颜色。 如果我们选择一组红色字母，则必须选择一组大小相等的不相交的绿色字母。 因此，我们能做的最好的就是选择尽可能多的不同字母并将它们分成相等的两半。 限制因素是至少出现一次的字母数量，即不同字符集的大小。 

让$d$是字符串中不同字符的数量。 我们可以为每个颜色的每个字符分配最多一次出现，因此我们最多可以使用$d$每种颜色的字母组合在一起。 由于颜色的大小必须相等，因此我们能做的最好的就是将它们配对，最多给出$\lfloor d/2 \rfloor$红色字符。 

这也符合直觉：我们本质上是在形成一对不同的字母，每一对贡献一个红色和一个绿色。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解分配| O(3^n·n) | O(3^n·n) | O(n) | 太慢了|
 | 计算不同字符 | 每次测试 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取每个测试用例的字符串并计算其中出现的不同字符集。 此步骤捕获所有可用的“资源”，因为由于每种颜色内的唯一性限制，字符的重复不会增加灵活性。 
2.让$d$是不同字符的数量。 现在我们来推断可以从这些字符中形成多少对颜色。 
3. 计算$k = d // 2$。 这表示从可用的不同字符中形成尽可能多的不相交的红绿对。 
4. 输出$k$作为测试用例的答案。 

关键的推理步骤是每个红色字符必须与不同的绿色字符匹配，并且任何字符都不能在颜色中重复使用。 因此，每个有效的贡献单位消耗两个不同的字母。 

### 为什么它有效

 该算法依赖于以下不变量：每个绘制的字符对应于唯一的字母颜色对，并且每个字母最多可以为每种颜色贡献一个这样的对。 由于只有$d$不同的字母，我们最多可以创建$d$两种颜色的可用分配总数。 由于颜色必须平衡，因此每个有效的解决方案每单位贡献消耗两个不同的字母，一个红色和一个绿色。 任何超越的尝试$d//2$需要重复使用某种颜色的字母或超出可用的不同字母表，这两者都违反了约束。 因此，计算值既是可实现的，也是最大的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    d = len(set(s))
    print(d // 2)
```该解决方案将每个测试用例简化为计算一组字符。 这`set(s)`操作会自动删除重复项，直接对重复字母不提供额外可用容量的约束进行建模。 

除以二反映了红色和绿色计数必须相等的要求，因此每个可用单位消耗两个不同的字母。 

一个微妙的点是我们永远不需要跟踪频率。 即使一个角色出现 10 次，它仍然只贡献 1 个可能的红槽和 1 个绿槽。

def run(inp: str) -> str:

 ## 边缘情况

 对于像这样的单字符字符串`"a"`，不同集合大小为 1，因此算法计算$1 // 2 = 0$。 这符合这样一个事实：我们不能将一个字母同时分配给红色和绿色，同时保持它们不同。 

对于完全重复的字符串，例如`"xxxxxx"`，不同的集合是`{x}`,再次给予$k = 0$。 即使存在许多位置，每种颜色内部的唯一性约束也会将它们全部折叠成单个可用元素，并且平衡会阻止任何分配。 

对于所有不同字符的字符串，例如`"abcdef"`，集合大小为 6，产生$k = 3$。 我们可以明确地将字母分成两组，每组三个，每组都有不同的字母，完全满足所有约束。
