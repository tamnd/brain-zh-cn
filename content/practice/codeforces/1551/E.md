 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并且允许我们重复地从中删除元素。 每次删除都会压缩数组，以便索引始终保持连续。 在所有删除之后，我们查看值与索引匹配的位置，这意味着我们希望在最终数组中尽可能多的“固定点”。 

目标不是最大化固定点，而是至少达到`k`同时最大限度地减少我们删除的元素数量。 

一个关键的微妙之处是删除元素会将所有索引更改为右侧。 所以一个元素是否成为不动点不仅取决于它的值，还取决于它之前发生了多少次删除。 

对于每个测试用例的二次或接近二次解，约束足够小。 每个测试都有`n ≤ 2000`，和总计`n`跨测试也≤ 2000。这强烈表明`O(n^2)`或者`O(n^2 log n)`解决方案是可以接受的，而每次测试任何立方体都是不必要的。 

如果我们试图贪婪地模拟删除而不考虑索引变化，那么天真的陷阱就会立即出现。 例如，删除元素会更改所有后面的位置，因此根据原始索引检查固定点是无效的。 

另一个微妙的边缘情况是当答案不可能时。 例如，如果所有值相对于索引都非常大，即使在删除之后，我们也可能永远无法将足够的值与位置对齐。 一个小例子是`a = [5, 5, 5]`,`k = 2`。 无论我们如何删除，我们都无法创建足够的价值等于索引的位置。 

## 方法

 强力解释是：尝试保留元素的每个子集，模拟结果数组，并计算固定点。 这显然是指数级的，因为有`2^n`子集，即使经过修剪，它对于`n = 2000`。 

我们需要一个更结构化的视图来了解删除序列的实际作用。 

不要考虑删除，而是翻转视角：我们正在选择保留的子序列。 假设我们将元素保留在位置`i1 < i2 < ... < im`。 在最终的数组中，这些成为位置`1..m`。 原始索引处保留的元素`i`如果其值等于其在保留元素中的新位置，则成为固定点。 

所以对于位置上保留的元素`i_j`，它贡献一个固定点，如果`a[i_j] = j`。 

这将问题转化为选择一个我们想要最大化索引数量的子序列`j`满足`a[i_j] = j`。 但指数`j`取决于我们在它之前保留了多少元素。 

更有用的转换是考虑每个候选固定点之前的删除。 假设我们想要某个位置`i`成为最终数组中的固定点。 如果我们保留`a[i]`，那么它的最终位置等于`i - deletions_before_i`。 为了修复它，我们需要：`a[i] = i - deletions_before_i`， 所以`deletions_before_i = i - a[i]`。 

这意味着每个索引`i`强加了一个要求：我们必须准确删除`i - a[i]`选择它作为固定点之前的元素。 此外，该值必须是非负的，否则不可能使其成为固定点。 

现在问题变成至少选择`k`索引，每个索引都有一个所需的“之前的删除预算”，以便这些要求在顺序上保持一致。 如果我们以递增索引顺序选择固定点，则它们所需的删除必须以兼容的方式非递减。 

我们可以将其建模为索引上的 DP：对于每个位置，我们考虑是否选择它作为固定点或跳过它，同时跟踪我们已经形成了多少固定点以及我们有效使用了多少删除。 

一种更清晰的优化出现了：对于每个元素，我们计算一个“成本”，即在修复它之前必须发生多少次删除。 然后我们尝试至少选择`k`元素按递增索引顺序排列，以便可以按顺序满足这些成本。 该问题简化为选择具有可行性约束的子序列，这自然可以通过 DP 来处理。 

我们定义`dp[i][j]`作为前缀中使用的最小删除数`i`获得`j`固定点。 过渡自`i-1`到`i`，我们要么跳过`i`（如果我们删除它，则删除量增加 1），或者如果在给定当前删除量的情况下可行，则将其保留为固定点。 

关键的见解是可行性仅取决于当前删除计数是否等于`i - a[i]`当我们决定接受它时。 

这个DP是`O(n^2)`每次测试。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 对于每个索引`i`，计算要求`need[i] = i - a[i]`。 如果`need[i] < 0`，这个位置永远不可能成为固定点，所以我们忽略它作为候选点。 
2. 构建动态规划表，其中`dp[j]`表示精确实现所需的最小删除次数`j`到目前为止固定点。 
3. 初始化`dp[0] = 0`和所有其他状态为无穷大。 没有固定点不需要删除。 
4. 从左到右迭代索引。 对于每个指标，我们考虑两种选择。 
5. 第一个选择是跳过该元素。 这对应于删除它，这会将所有状态的删除计数增加 1。 该模型删除的元素会影响未来的指数。 
6. 第二种选择是以单元为不动点。 仅当当前删除计数与其要求匹配时这才有效`need[i]`。 如果匹配，我们更新`dp[j+1]`使用`dp[j]`无需添加额外的删除，因为所需的删除已经被考虑在内。 
7. 处理完所有元素后，我们寻找任何`j ≥ k`这样`dp[j]`是有限的。 答案是其中最少的删除。 

### 为什么它有效

 每个固定点在原始索引、最终位置和之前的删除数之间施加严格的对齐条件。 DP 强制要求，每当我们选择一个元素作为固定点时，前缀删除必须与该元素所需的完全匹配。 由于删除随着我们前进而单调增加，并且我们仅在索引中向前过渡，因此 DP 保持所有选定固定点之间的一致性。 任何无效的排序都会被排除，因为不匹配的删除会计算块转换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**9

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    # dp[j] = minimum deletions to get j fixed points so far
    dp = [INF] * (n + 1)
    dp[0] = 0

    for i in range(n):
        ndp = [INF] * (n + 1)

        need = i + 1 - a[i]  # 1-based index logic

        for j in range(n):
            if dp[j] == INF:
                continue

            # option 1: skip i (delete it)
            ndp[j] = min(ndp[j], dp[j] + 1)

            # option 2: take as fixed point if feasible
            if need >= 0 and dp[j] == need:
                ndp[j + 1] = min(ndp[j + 1], dp[j])

        dp = ndp

    ans = min(dp[k:])
    print(-1 if ans == INF else ans)

t = int(input())
for _ in range(t):
    solve()
```DP 数组按索引重建，以避免不同选择的状态混合。 条件`dp[j] == need`在考虑了早期删除后，对固定点有效所需的精确对齐约束进行编码。 

一个微妙的实现点是使用`i + 1 - a[i]`而不是`i - a[i]`，因为 Python 使用基于 0 的索引，而条件自然是基于 1 的。 

第二个微妙之处是，跳过一个元素总是会增加删除计数，这使得后面的元素可以移动到位。

 ## 边缘情况

 一种边缘情况是当`a[i]`对于它的位置来说太大了。 例如`i=2, a[i]=5`给出`need < 0`，所以该元素不可能变得固定。 算法自然会忽略它，因为条件`need >= 0`失败。 

另一个边缘情况是当所有元素都已经满足`a[i] = i`。 在这种情况下`need = 0`到处都是，所以每个元素都是有效的不动点，不需要任何删除。 DP将允许采取任何`k`其中零成本，产生答案`0`。 

最后一个边缘情况是`k = 1`。 该算法正确地简化为找到满足约束的任何单个索引，并返回对齐一个元素所需的最小删除，根据结构，该删除为零或很小的移位成本。
