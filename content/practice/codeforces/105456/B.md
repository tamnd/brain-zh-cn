 ## 解决方案
 ## 问题理解

 我们得到一串代表短信的小写字母。 佩德罗需要通过准确删除来缩短它$n - k$字符，同时保持其余字符的相对顺序不变。 在所有可能的长度子序列中$k$，我们想要的是字典顺序最小的那个。 

关键的限制是我们不允许对字符重新排序，只能删除它们。 因此，任务不是排序或重新排列，而是选择在字典顺序下最优的子序列。 

约束条件$n \le 100000$每个测试用例立即排除任何尝试所有子序列或使用任何指数或二次探索的解决方案。 甚至一个$O(nk)$当两者都很大时，动态规划方法太慢。 我们被迫采用贪婪的结构，其中每个角色都是在接近恒定的摊销时间内决定的。 

当消息包含较长的递减序列或重复字母时，会出现微妙的边缘情况。 例如，在像这样的字符串中`dcba`和$k = 2$，总是采用最小的可用下一个字符而不考虑未来可行性的幼稚策略可能会失败，因为过早地选择可能会为剩余插槽留下太少的字符。 

当出现另一个问题时$k$非常小，比如$k = 1$，其中答案只是整个字符串中的最小字符，并且当$k = n$，其中不需要删除。 任何正确的算法都必须自然地处理这些边界情况，而没有特殊的大小写错误。 

## 方法

 一个蛮力的想法是生成每个长度的子序列$k$，计算其字典顺序，并取最好的。 这在概念上是正确的，因为它探索了所有有效答案，但子序列的数量是$\binom{n}{k}$，即使对于中等强度的情况来说，这也会变得天文数字般大$n$。 为了$n = 100000$，这是完全不可行的。 

更结构化的动态规划方法可能会定义$dp[i][j]$作为长度的最佳子序列$j$从一开始$i$人物。 虽然这在逻辑上可行，但它需要重复存储或比较字符串，导致至少$O(nk)$转变和潜在的$O(k)$每个转换的比较，这远远超出了限制。 

关键的观察是，一旦我们确定较小的字符可以替换子序列中较早的较大字符，我们就永远不需要重新考虑字符。 如果我们从左到右构建答案，我们只需要确保在每个位置，我们选择仍然允许我们完成有效长度子序列的最小可能字符$k$。 

这自然会导致贪婪的单调结构：我们扫描字符串并维护一个表示当前最佳前缀的结构，删除比我们以后仍然可以选择的字符更糟糕的字符。 这正是经典的“删除数字/具有固定长度的字典最小子序列”模式，使用类似堆栈的结构有效实现。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(k) | 太慢了 |
 | 最优贪婪堆栈 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们使用代表当前选择的子序列的堆栈来构建答案。 

1. 初始化一个空栈，并设置一个计数器来记录我们还需要删除多少个字符，即$n - k$。 这跟踪了我们的灵活性：每次删除都使我们能够改进字典顺序。 
2. 从左到右遍历字符串的字符。 对于每个字符，我们考虑它是否可以替换当前部分答案中较早的字符。 
3. 当堆栈非空时，堆栈中的最后一个字符按字典顺序大于当前字符，并且我们仍然有可用的删除操作，弹出堆栈。 此步骤确保当更好的字符可以更早出现时，我们不会保留更差的字符，从而尽早改善字典顺序。 
4. 将当前字符压入堆栈。 这扩展了当前候选子序列。 
5. 如果我们用完了允许的删除，但堆栈中仍然有多余的字符，则我们无法删除更多字符，因此我们只需继续推送，并在需要时进行修剪。 
6. 处理完所有字符后，堆栈中可能包含多个字符$k$如果我们从未在最佳位置使用所有删除，则字符。 在这种情况下，将堆栈截断到第一个$k$人物。 
7. 生成的堆栈是按字典顺序排列的长度最小的子序列$k$。 

这样做的原因是，每次我们删除一个字符时，只有当稍后出现一个严格较小的字符时，我们才会这样做，并且我们仍然有足够的剩余字符来完成长度$k$顺序。 这保证了我们永远不会阻止自己形成有效的答案，同时始终尽早改进字典顺序。 

### 为什么它有效

 在扫描的任何前缀处，堆栈表示在我们仍然可以将其扩展到长度的约束下使用已处理字符的最佳可能子序列$k$。 贪婪删除步骤保持了堆栈单调的不变性，即如果删除预算允许校正，则前面的字符不会大于后面的字符。 因为每个字符最多被压入和弹出一次，所以每个决策都是局部最优的并且与字典顺序全局一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()

        remove = n - k
        stack = []

        for c in s:
            while stack and remove > 0 and stack[-1] > c:
                stack.pop()
                remove -= 1
            stack.append(c)

        # If still have removals left, remove from end
        # (only needed if no better pops occurred)
        while remove > 0:
            stack.pop()
            remove -= 1

        print("".join(stack[:k]))

if __name__ == "__main__":
    solve()
```实现直接遵循基于堆栈的贪婪构造。 变量`remove`跟踪仍然允许删除的次数。 内部 while 循环是关键部分：它通过删除比当前字符大的先前字符来强制字典顺序改进。 

最后的修剪步骤是必要的，因为某些情况在扫描期间永远不会触发足够的有益删除，特别是当字符串已经增加或部分增加时。 如果没有这一步，堆栈的长度可能会超过$k$。 

切片`stack[:k]`即使在所有贪婪的决策之后，也确保最终输出严格遵守所需的长度。

 ## 边缘情况

 一个关键的边缘情况是当字符串严格递减时，例如`dcba`和$k = 2$。 当出现较小的字符且删除预算可用时，该算法会不断弹出，从而产生稳定的最小前缀。 

输入：```
4 2
dcba
```执行：

 堆栈演变为`d -> c -> b`，当较小的字符到达时，删除操作会立即丢弃较大的前缀。 最后的修剪确保恰好保留两个字符，产生`ba`，按字典顺序，它是所有长度为 2 的子序列中最小的。 

另一个边缘情况已经对输入进行了排序，例如`abcde`和$k = 3$。 由于堆栈已经在增加，因此不会触发任何删除操作，并且最终截断仅采用前三个字符，从而产生`abc`，这是最佳的，因为任何稍后的包含都会使字典顺序恶化。 

这两种情况证实了算法在需要积极删除和没有删除有益的情况下都能正确适应。
