 ## 解决方案
 ## 问题理解

 我们给出了三个字符的计数，即必须使用字母 A、B 和 C 的次数。对于每个测试用例，任务是完全使用这些字符构造一个字符串，使该字符串向前和向后读取相同的字符串，并且在所有有效的此类字符串中，我们必须输出按字典顺序最小的字符串。 如果所有字符都无法组成回文，则答案为“ROP”。 

回文施加了严格的结构约束：对称位置上的字符必须匹配。 这立即意味着频率分布不是任意的。 最多一种字符类型可以出现奇数次，因为回文最多有一个中心字符而没有镜像伙伴。 

约束足够小，每个测​​试用例只需要在字母表大小方面进行恒定或线性工作。 由于每个测试用例的字符总数最多为 3000 个，并且测试用例最多为 1000 个，因此任何直接构建字符串的方法都足够快。 我们无法承受的是尝试所有排列或执行阶乘式构造。 

一种常见的故障模式是忽略奇偶校验。 例如，如果我们尝试贪婪地构建一个回文而不首先检查可行性，我们最终可能会构建半个无法一致镜像的字符串。 

当存在多个奇数计数时，会出现第二种微妙的边缘情况。 例如，像 1 1 1 这样的输入有 3 个奇数计数。 无法在中心放置多个奇数字符，因此不存在解决方案。 

## 方法

 一种强力解释是生成多组字母的所有排列并过滤回文字母，然后选择字典顺序最小的一个。 这在概念上很简单：我们用给定的计数枚举 A、B 和 C 的每种排列，检查它是否是回文，并跟踪最小的字典结果。 

问题是组合爆炸。 如果总长度为 N，则不同排列的数量为 N！ 除以重复阶乘。 即使对于像 30 这样的中等 N，这也变得完全不可行。 回文检查的复杂度为 O(N)，因此总复杂度变为阶乘规模。 

关键的观察是回文完全由其前半部分加上可能的中间字符决定。 一旦我们决定每个字母中有多少进入左半部分，右半部分就被强制。 这将问题从排列搜索变成了约束计数问题。 

我们只需要决定有多少个A、B、C进入左侧，这样剩余的计数就可以正确镜像。 这意味着对于每个字符，两侧使用的数字必须是偶数，任何剩余的奇数字符（最多一种类型）都位于中心。 构造完左半部分后，通过从最小字符到最大字符贪婪地填充它来实现字典序最小化。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力排列 | O(N!) | O(N) | 太慢了 |
 | 从一半计数构建 | O(N) | O(N) | 已接受 |

 ## 算法演练

 我们将问题简化为确定回文的可行性，然后构建最小的字典式回文。

1. 计算 A、B、C 中有多少个是奇数。 如果多个计数为奇数，则不存在回文。 这是因为每个回文最多有一个不成对的中间字符。 
2. 识别中间字符（如果存在）。 如果其中一个计数为奇数，则该字母将成为回文的中心。 
3. 除以二将所有计数转换为半计数。 这些代表每个字符的数量将出现在回文的左侧。 
4. 通过按字典顺序放置字符来构建回文的左半部分，始终首先使用所有可用的 A，然后是 B，然后是 C。这种贪婪顺序可确保整个字符串按字典顺序最小，因为较早的位置主导字典顺序比较。 
5. 将最终答案构建为左半部分+中间部分（如果有）+反转的左半部分。 

正确性取决于这样一个事实：一旦固定了一半的计数，左半部分内的顺序就直接决定了完整回文的字典顺序。 

### 为什么它有效

 任何有效的回文都由其左半部分和可选的中心字符唯一确定。 可行性约束仅限制奇偶性而不限制排序。 由于字典比较是从左到右决定的，因此按字母顺序贪婪地最小化左半部分可以保证最小的可能完整字符串。 右半部分的重新排列不能改变这种顺序，因为它完全由对称性决定。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        a, b, c = map(int, input().split())
        counts = [a, b, c]
        letters = ['A', 'B', 'C']
        
        odd = sum(x % 2 for x in counts)
        if odd > 1:
            out.append("ROP")
            continue
        
        mid = ""
        for i in range(3):
            if counts[i] % 2 == 1:
                mid = letters[i]
                counts[i] -= 1
                break
        
        half = [counts[i] // 2 for i in range(3)]
        
        left = []
        for i in range(3):
            left.append(letters[i] * half[i])
        
        left = "".join(left)
        right = left[::-1]
        
        out.append(left + mid + right)
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案首先使用奇偶校验验证回文在结构上是否可能。 然后，它仅在需要时分配一个中间字符，确保恰好减少一个奇数计数。 半计数代表强制对称，并且以固定的字典顺序构建左侧可确保最小性。 最后通过镜像完成回文。 

一个微妙的点是我们在减半之前从奇数中减去一。 这确保了中心字符不会干扰对称性。 另一个重要的细节是词典编排最优性不需要回溯，因为一旦固定了一半的顺序，所有选择都是独立的。 

## 工作示例

 ### 示例 1

 输入：```
2

2 2 2
```对于每个测试用例：

 | 步骤| 计数（A、B、C）| 奇数计数 | 中| 半数 | 左|
 | ---| ---| ---| ---| ---| ---|
 | 1 | 1,0,0 | 1,0,0 | 1 | 一个 | 0,0,0 | “” |

 对于第一种情况，将 A 置于中心后所有计数都是偶数，因此结果为“A”。 对于第二种情况，存在多个奇数，无法形成回文，因此输出为“ROP”。 

这证实了奇偶校验规则正确地检测了可行性，并且该构造可以处理平凡的单字母回文。

这显示了该算法如何自然地将对称构造与中心处理分开而不会产生歧义。

 ## 边缘情况

 用于输入`0 0 5`，算法检测到一个奇数计数 (C)，将其分配给中心，将其减少到 4，并构建半计数 (0,0,2)。 左半部分变成“CC”，产生“CCCCC”。 这证实了对纯单字符优势的正确处理。 

用于输入`1 1 1`，所有三个计数都是奇数，因此算法在尝试构造之前立即返回“ROP”。 这表明可行性检查可以防止错误的强制放置。 

用于输入`2 0 3`，算法将 C 分配给中心，留下平衡的一半。 结构“AC + C + CA”同时确认了对称性和字典顺序的正确性。
