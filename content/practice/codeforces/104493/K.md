 ## 解决方案
 ## 问题理解

 每个参赛者最终都会得到一根长度相同的字符串`m`。 该字符串已经按非降序排序，因此它由相同的字符组成：一定数量的`'a'`，然后一些`'b'`，依此类推，直到`'z'`。 

任务是回答许多问题。 每个查询给出两个参赛者，我们必须计算有多少个位置`i`两个字符串中具有相同的字符。 换句话说，我们计算两个排序字符串之间的汉明相似度：有多少索引完全匹配。 

这些限制在结构上很重要。 总输入大小满足`n · m ≤ 5 × 10^5`，因此我们可以对所有字符串的所有字符进行大致线性的预处理。 然而，查询的数量可以大到`10^6`，这会立即排除任何针对每个查询扫描完整字符串的解决方案。 甚至`O(m)`每个查询都会太慢。 

重要的隐藏结构是每个字符串都已排序。 这意味着每个字符串完全由每个字母的计数决定，更重要的是，每个字母在字符串中占据一个连续的段。 这将问题从任意数组的位置比较转变为间隔上的重叠查询。 

一个天真的错误是每个查询都逐个字符地比较字符串。 这在逻辑上是可行的，但需要最多`10^6 × 5×10^5`在最坏的情况下进行操作，这是不可行的。 

另一个微妙的陷阱是仅比较字符频率。 这还不够，因为频率平等并不意味着位置平等。 例如，`"aabbcc"`和`"abcabc"`具有相同的计数，但匹配的索引要少得多。 

关键是保留由排序顺序引起的位置结构。 

## 方法

 暴力解决方案很简单：对于每个查询，迭代所有`m`位置和匹配次数。 这是正确的，因为我们直接比较定义。 然而，随着高达`10^6`可能有长度的查询和字符串`5×10^5 / n`，这会导致最坏情况的解决`O(Q · m)`，这远远超出了可接受的范围。 

关键观察来自排序属性。 由于每个字符串都是非递减的，因此每个字符形成一个连续的块。 例如，一个字符串可能看起来像`aaaabbbbcc`。 

我们可以考虑每个角色的间隔，而不是考虑单个位置。 对于每个字符串和每个字母`c`，我们可以计算索引段，其中`c`出现。 然后，当比较两个字符串时，当且仅当两个字符串位于该位置的同一字符块中时，该位置才有助于得出答案。 这将问题简化为对相应字符间隔的重叠进行求和。 

对于每个字母，我们计算其块在两个字符串之间重叠的程度。 由于每个字母恰好出现在每个字符串的一个连续间隔中，因此可以在恒定时间内计算该字母的贡献。 有了 26 个字母，每个查询就变成`O(26)`。 

这减少了从扫描完整字符串到比较恒定数量的间隔的整个问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(Q·m) | O(1) | O(1) | 太慢了|
 | 最佳| O(n·m + 26·Q) | O(n·26) | 已接受 |

 ## 算法演练

 1. 对于每个字符串，计算每个字符出现的次数。 由于字符串已排序，因此这些计数对应于按顺序排列的连续段`'a'`到`'z'`。 
2. 将每个字符串转换为 26 个位置上的间隔。 按顺序扫描字符时，为每个字母块分配开始和结束索引。 这会产生数组`L[i][c]`和`R[i][c]`, 代表where字符`c`生活在字符串中`i`。 
3. 对于每个查询比较字符串`s`和`t`，迭代所有 26 个字母。 
4. 对于每个字母`c`，计算两个区间的重叠：

 重叠是`max(0, min(Rs[c], Rt[c]) - max(Ls[c], Lt[c]) + 1)`。 
5. 对所有字母的重叠进行求和以获得匹配位置的数量。 
6. 输出每个查询的结果。 

步骤 4 背后的原因是，仅当两个字符串将相同的字符分配给该位置时，该位置才对答案有贡献。 由于每个字符在两个字符串中恰好占据一个连续块，因此这些块的交集精确地计算了匹配索引。 

### 为什么它有效

 每个字符串划分索引范围`[1, m]`分为 26 个不相交的间隔，每个字符一个（可能为空）。 在任何位置`i`，每个字符串中恰好有一个区间包含`i`，并且该间隔唯一地确定该位置处的字符。 

位置匹配`i`当两个字符串选择相同的间隔标签时恰好发生`i`。 因此，对相等位置进行计数就简化为对相应字符间隔的两两交集进行求和。 任何位置都不能计算两次，因为字符串中不同字母的间隔是不相交的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_intervals(s):
    m = len(s)
    L = [0] * 26
    R = [0] * 26

    i = 0
    pos = 1
    while i < m:
        c = ord(s[i]) - 97
        start = pos
        while i < m and ord(s[i]) - 97 == c:
            i += 1
            pos += 1
        end = pos - 1
        L[c] = start
        R[c] = end

    return L, R

n, m = map(int, input().split())
strings = [None] * n
intervals = [None] * n

for i in range(n):
    s = input().strip()
    strings[i] = s
    intervals[i] = build_intervals(s)

q = int(input())
out = []

for _ in range(q):
    a, b = map(int, input().split())
    a -= 1
    b -= 1

    La, Ra = intervals[a]
    Lb, Rb = intervals[b]

    ans = 0
    for c in range(26):
        left = max(La[c], Lb[c])
        right = min(Ra[c], Rb[c])
        if left <= right:
            ans += right - left + 1

    out.append(str(ans))

print("\n".join(out))
```预处理步骤通过扫描一次将每个排序的字符串转换为 26 个字符间隔。 这是安全的，因为排序顺序保证每个字符有一个连续的块，因此没有字符需要多个段。 

然后，每个查询仅使用每个字符的常量工作。 重叠公式为标准区间交集，`+1`考虑包容性索引。 

一个常见的实现错误是忘记了某些字母根本没有出现在字符串中。 在这种情况下，它们的间隔保持为零长度，并且重叠公式自然贡献为零，因为`left > right`。 

## 工作示例

 考虑两个字符串：`s = "aaabbc"`

`t = "aabbbc"`我们计算间隔：

 对于`s`:

 | 信| 间隔|
 | --- | --- |
 | 一个 | [1,3]|
 | 乙| [4,5]|
 | c | [6,6]|

 为了`t`:

 | 信| 间隔|
 | --- | --- |
 | 一个 | [1,2]|
 | 乙| [3,5]|
 | c | [6,6]|

 现在计算重叠：

 | 信| 重叠|
 | --- | --- |
 | 一个 | [1,2] → 2 |
 | 乙| [4,5] ∩ [3,5] = [4,5] → 2 |
 | c | [6,6] → 1 |

 总答案是`2 + 2 + 1 = 5`。 

这表明，尽管内部排列不同，但匹配位置纯粹是通过区间交叉来捕获的。 

现在考虑：`s = "aaaa"`

`t = "bbbb"`间隔：`s: a[1,4]`

`t: b[1,4]`所有重叠部分都是空的，所以答案是`0`，这符合直觉，因为没有位置共享相同的字符。

 ## 边缘情况

 一种微妙的边缘情况是字符未出现在其中一个字符串中。 在这种情况下，其间隔保持未设置。 该算法仍然有效，因为`L[c]`和`R[c]`默认为`0`，产生无效区间，以及交集条件`left <= right`失败，贡献为零。 

另一种情况是字符串仅包含一个字符，例如`"aaaaa"`。 那么只有一个间隔是非空的，所有其他字母保持不活动状态。 针对此类字符串的查询仍然可以正常工作，因为所有匹配贡献都集中在该单个间隔中，并且所有其他字母通过空重叠自然不会贡献任何内容。
