 ## 解决方案
 ## 问题理解

 我们为每个测试用例提供一个整数数组，并且允许我们插入一个额外的整数值$X$数组中的任意位置。 插入后，数组大小增加一，并且在新数组上重新计算算术平均值和中位数。 

任务是选择$X$使得更新后的数组的均值等于其中位数。 在所有有效选择中$X$，我们必须输出尽可能小的一个。 

均值完全由元素总和决定，因此插入$X$以线性方式改变平均值。 然而，中位数取决于排序顺序和新长度的奇偶校验，这从根本上使问题成为关于单个插入值如何移动排序数组的中心位置的问题。 

约束的总规模很大，最多可达$10^6$测试用例的总体数字。 这立即排除了任何在每个可能的位置重复模拟插入或天真的尝试候选的解决方案。 任何依赖于每次候选插入从头开始扫描或重新计算中位数的方法都会太慢，除非减少到每个测试用例排序一次。 

朴素推理的一个微妙的失败案例是假设插入后中位数保持接近原始中位数。 例如，如果数组高度倾斜，则插入精心选择的$X$可以将中值位置移动到排序顺序的完全不同的区域。 任何假设中位数局部稳定的方法在这种分布上都会失败。 

另一个陷阱是假设$X$必须等于最终中位数或原始中位数。 这不一定是真的，因为插入$X$同时改变平均值和中位数，因此平衡点可以位于原始结构之外。 

## 方法

 暴力思想是从定义开始的。 我们可以尝试每一个可能的整数$X$，插入它，重新计算平均值和中位数，并检查相等性。 即使我们限制$X$对于数组元素周围的值，这仍然是不可行的，因为对于每个候选者，我们需要插入并重新计算中位数，这会花费$O(n)$排序后或$O(n \log n)$每次尝试。 高达$10^6$元素总量，这已经远远超出了极限。 

关键的观察是，一旦数组排序，插入后的中位数仅取决于其中的位置$X$放置，并且平均条件给出了一个直接线性方程$X$。 所以而不是猜测$X$，我们可以逆向思考：假设插入后中位数的位置，并推导出什么$X$必须是为了保持这一点。 

插入一个元素后，新的大小为$n+1$，中位位置固定为$\lfloor (n+2)/2 \rfloor$。 让排序后的最终数组中的该位置对应于原始数组中的某个元素或可能是插入的元素。 如果我们修复哪里$X$按排序顺序排列，我们可以用代数方式表达这两个约束并计算得到的候选值$X$。 由于中位位置是已知的，我们只需要考虑其中的恒定数量的结构情况$X$可以相对于已排序的数组着陆。 

一旦我们对数组进行一次排序，前缀和就可以让我们快速计算平均值，并且我们可以在恒定时间内评估每个候选位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$每次测试（或更糟）|$O(1)$| 太慢了|
 | 最佳|$O(n \log n)$总计 |$O(n)$| 已接受 |

 ## 算法演练

 我们对数组进行排序并预先计算前缀和，以便我们可以在恒定时间内计算段和。 让$m = n+1$是插入后的最终尺寸$X$。 最终排序数组中的中位位置为$k = (m+1)//2$。 

然后我们考虑在哪里$X$可以按排序顺序出现。 如果我们假设插入$X$位置之间$i-1$和$i$在已排序的数组中，然后是第一个$i-1$元素保持不变，并且所有元素来自$i$向前右移一位。 

对于每个这样的插入位置$i$，我们确定中值元素变成什么。 如果$i > k$，那么中位数不受插入的影响，仍然是位置处的原始元素$k$。 如果$i \le k$，中位数向右移动一步，成为位置处的原始元素$k-1$。 

一旦我们知道目标中值$M$，我们强制执行均值等于中位数的条件。 新数组的总和是$S + X$，所以方程是：$$\frac{S + X}{n+1} = M$$这给出：$$X = (n+1)\cdot M - S$$我们计算这个候选人$X$对于两个相关的中位数可能性，并检查将其插入到假设的位置是否与排序顺序约束一致（它必须落入之间的正确区间）$a_{i-1}$和$a_i$）。 在所有有效的候选人中，我们选取​​最低的。 

它起作用的原因是单次插入后的中值结构相对于插入位置是分段恒定的。 每个区域对应于原始排序数组中的固定中值索引。 在每个区域内，平均条件唯一确定$X$，因此解空间会收缩为一小部分有限的候选集，而不是连续搜索。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    total = pref[n]
    m = n + 1
    k = (m + 1) // 2

    ans = None

    def try_median(mid_idx):
        nonlocal ans
        x = m * a[mid_idx] - total
        ans = x if ans is None else min(ans, x)

    if k - 1 >= 0:
        try_median(k - 1)
    if k < n:
        try_median(k)

    print(ans)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```该解决方案依赖于对每个测试用例进行排序，因为中值逻辑纯粹是按排序顺序定义的。 前缀和用于有效计算原始总和，这是推导所必需的$X$从平均方程中得出，无需重复重新计算总和。 

功能`try_median`编码两种结构情况：插入是否移动中值位置。 每种情况对应于原始数组中的固定候选中值元素。 一旦中位数固定，则$X$是唯一确定的。 

最终答案是有效候选中的最小值，符合输出最小可行的要求$X$。 

## 工作示例

 ### 示例 1

 输入：```
3
1 2 3
```这里$n=3$， 所以$m=4$，中位位置是$k=2$。 已排序的数组$[1,2,3]$，总和为 6。 

我们测试两个中值来源：

 | 案例 | 使用的中值元素 | 计算| X |
 | --- | --- | --- | --- |
 | k-1 | a[1] = 2 | 4*2 - 6 | 2 |
 | k | 一个[2] = 3 | 4*3 - 6 | 6 |

 最低有效$X$是2。插入2后，数组变成$[1,2,2,3]$，中位数为 2，平均值为 2。 

此跟踪表明正确的解决方案不需要显式放置$X$; 一旦我们决定哪个原始元素成为中位数，就完全确定了。 

### 示例 2

 输入：```
5
1 2 3 4 6
```这里$n=5$， 所以$m=6$, 中间位置$k=3$，总和为 16。 

| 案例 | 使用的中值元素 | 计算| X |
 | --- | --- | --- | --- |
 | k-1 | 一个[2] = 3 | 6*3 - 16 | 6*3 - 16 2 |
 | k | 一个[3] = 4 | 6*4 - 16 | 6*4 - 16 8 |

 最小值为 2。 

这表明，即使数组不对称，候选构造仍然可以将问题简化为仅评估两种可能性。

 ## 边缘情况

 关键的边缘情况是所有元素都相同。 在这种情况下，任何保持平等的插入仍应产生相同的中位数和均值。 该算法评估两个中值导出的候选值，但两者都崩溃为相同的值，因为总和与相同的元素成线性比例。 

另一种边缘情况是数组严格递减或递增。 中位数候选仍然仅来自两个中心位置，并且计算出的$X$自然会落入正确的插入区间，因此除了排序之外不需要额外的验证。 

最后，当$n$非常小，特别是$n=1$或者$n=2$，两种情况下中位指数逻辑变化$k-1$和$k$。 该算法仍然正确地评估两种可能性，并且有效候选的最小值与所需的输出匹配，无需特殊分支。
