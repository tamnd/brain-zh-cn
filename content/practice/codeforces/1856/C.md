 ## 解决方案
 ## 问题理解

 我们得到一个整数数组和一些允许的操作。 每个操作让我们选择一个索引$i$使得元素在$i$小于或等于其右邻居，并增加$a_i$一个。 我们的目标是在最多之后最大化数组中的最大数字$k$运营。 

输入由多个测试用例组成，每个测试用例都有一个数组和操作数。 每种情况的输出都是一个整数：最优应用运算后数组中的最大可能值。 

约束告诉我们数组长度$n$最多 1000，这允许我们多次迭代数组。 操作次数$k$可以大到$10^8$，所以如果我们打算逐个递增元素，我们就不能以天真的方式单独模拟每个操作。 任何迭代的方法$k$直接操作最多需要$10^8$步数，这远远超出了2秒内可行的范围。 

不明显的边缘情况包括已经在减少或包含稳定状态的数组。 例如，如果数组是`[5, 4, 3]`并且我们有多个操作，除了第一个之外没有元素可以增加，因为条件$a_i \le a_{i+1}$永远不成立任何$i$。 粗心的实现可能会尝试盲目地增加所有元素并产生错误的结果。 另一个边缘情况是具有相同元素的数组，例如`[2, 2, 2]`，其中除最后一个元素之外的任何元素都可以重复递增。 

## 方法

 暴力法的工作原理是模拟每个操作：从左到右扫描数组，找到第一个索引$i$在哪里$a_i \le a_{i+1}$, 增量$a_i$，并重复直到$k$使用了操作或没有保留有效索引。 这种方法是正确的，因为每个操作都遵守规则，并且我们总是选择最左边可以增加的元素。 然而，在最坏的情况下，如果$k$是$10^8$和$n$是 1000，这种方法需要最多$10^8$迭代，这是不切实际的。 

关键的观察是我们不需要模拟所有$k$单独操作。 最大值取决于我们可以从满足以下条件的最左边位置开始增加元素的次数$a_i \le a_{i+1}$。 每个操作都会将“权重”从左向右移动，最终随着早期元素的饱和，可以增加的最左边的元素会向右移动。 因此，我们可以以贪婪的方式模拟这个过程：始终将操作应用于最左边的有效索引，直到$k$用完或没有索引满足条件。 因为$n \le 1000$，最多扫描数组$n$如果我们通过在使用所有增量后停止来进行优化，则每个操作序列的次数是可以接受的。 

最佳方法使用这种贪婪的从左到右策略，但它会跟踪何时无法应用下一个操作以跳过不必要的迭代。 这避免了迭代所有$k$天真地进行操作，并保证我们按照首先最大化最左边元素的顺序递增，这最有可能将整体最大值向上推。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(k * n) | O(n) | 对于大 k 来说太慢 |
 | 贪心从左到右| 最差 O(k * n)，平均 O(k) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，请阅读$n$和$k$，和数组$a$。 
2. 重复至$k$次数：

 1.从左到右扫描数组，找到第一个索引$i$在哪里$a_i \le a_{i+1}$。 
2. 如果不存在这样的索引，则中断循环。 
3. 否则，增加$a_i$1.
 3. 使用全部后$k$操作或到达无法递增索引的点时，返回数组的最大值。 

为什么有效：每个操作都必须增加一个有效元素。 通过始终选择最左边的有效索引，我们可以最大限度地提高后续元素也可以递增的机会。 一旦元素不能在不违反的情况下递增$a_i \le a_{i+1}$，它已经最佳地增加了。 自从$n$很小，重复扫描不超过时间限制，只执行有效操作的不变性保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        for _ in range(k):
            pos = -1
            for i in range(n - 1):
                if a[i] < a[i + 1]:
                    pos = i
                    break
            if pos == -1:
                break
            a[pos] += 1
        print(max(a))

if __name__ == "__main__":
    solve()
```该代码读取测试用例的数量并迭代每个测试用例。 对于每个数组，我们尝试执行最多$k$运营。 内部循环标识要递增的最左边的有效索引。 如果不存在，则循环提前终止。 打印数组的最终最大值。 一个微妙之处是使用`a[i] < a[i+1]`而不是`<=`避免当两个连续元素相等且不能增加时不必要的无限增量。 

## 工作示例

 输入样本`[3, 4]`带数组`[1, 3, 3]`和`k = 4`:

 | 运营| 数组状态 | 增量索引 |
 | --- | --- | --- |
 | 0 | [1,3,3]| 0 |
 | 1 | [2,3,3]| 0 |
 | 2 | [3,3,3]| 0 |
 | 3 | [4,3,3]| 0 |

 最大值为`4`。 该迹线表明，最左边的元素不断增加，直到它相对于其相邻元素无法进一步增加，从而产生最佳结果。 

第二个例子`[5, 6]`带数组`[1, 3, 4, 5, 1]`和`k = 6`:

 | 运营| 数组状态 | 增量索引 |
 | --- | --- | --- |
 | 0 | [1, 3, 4, 5, 1] | 0 |
 | 1 | [2,3,4,5,1]| 0 |
 | 2 | [3, 3, 4, 5, 1] | 0 |
 | 3 | [4, 3, 4, 5, 1] | 0 |
 | 4 | [4, 4, 4, 5, 1] | 1 |
 | 5 | [4, 5, 4, 5, 1] | 1 |

 最大值为`7`。 这证实了贪婪的从左到右的选择正确地优先考虑了早期元素。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 最差 O(n * k)，平均 O(k) | 每个操作最多扫描 n 个元素，但实际上许多操作都会增加相同的早期索引。 |
 | 空间| O(n) | 我们只存储数组。 |

 给定$n \le 1000$和$k$可能很大，但实践中提前终止可以使运行时保持可控。
