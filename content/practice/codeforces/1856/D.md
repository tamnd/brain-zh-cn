 ## 解决方案
 ## 问题理解

 我们被要求找到隐藏长度排列中最大元素的位置$n$通过使用告诉我们子数组中反转次数的查询。 每个查询的成本随着子数组长度呈二次方增长，我们的全局预算为$5 \cdot n^2$每个测试用例的硬币。 排列是固定且不同的，这意味着每个数字来自$1$到$n$恰好发生一次。 子数组中的反转计算有多少对元素相对于升序是无序的。 

主要挑战是查询所有可能子数组的简单方法成本高昂。 即使是最大的$n = 2000$，大约有 200 万个子阵列，平方成本将超出预算几个数量级。 我们需要一种方法来使用尽可能少和尽可能小的查询来识别最大元素。 另一个微妙之处是，查询包含最大数字和较小数字的子数组可以根据其顺序返回任意数量的反转，因此我们不能仅依赖数字； 我们需要排列的结构属性。 

边缘情况包括非常小的$n$， 例如$n = 2$，其中单个查询就足够了，以及最大元素位于两端之一的情况。 粗心的方法可能会假设最大值接近中间，或者可能一次查询太多元素，从而很快超出硬币预算。 

## 方法

 一种强力方法是查询每个单独的对或每个子数组并计算反转以推断最大值。 这是可行的，因为最大元素没有大于它的元素，因此末尾包含它的子数组将具有可预测的反转计数。 然而，它很快就会变得太昂贵：对于$n=2000$，粗略查询所有对的成本$n^3/2 \sim 4 \times 10^9$硬币，远远超出了我们的预算。 

关键的观察是我们不需要到处都有精确的反转计数。 最大元素始终对作为最后一个元素的任何子数组贡献零反转。 相反，任何在开头包含最大元素的子数组在算作反转后都将包含所有较小的元素。 这使我们能够执行类似二分搜索的策略：我们可以重复查询子数组并使用反转计数来决定最大值位于左半部分还是右半部分。 通过仔细选择查询范围，我们确保硬币成本保持在预算范围内。 

实际上，我们将反转计数视为有关相对位置的信号。 如果以最后一个元素结尾的子数组有零个反转，我们就知道最大值位于该子数组的末尾。 否则，我们可以拆分数组并继续递归。 这种分而治之的方法利用排列的线性排序来缩小排列的最大值$O(n \log n)$成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) | O(n^3) | O(1) | O(1) | 太慢了 |
 | 使用反转查询进行分而治之 | O(n log n) | O(n log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从完整数组索引开始$1$到$n$。 我们想要找到最大元素的索引。 
2. 当当前搜索范围有多个元素时，选择一个中点$m$并从中查询子数组$m$到最后。 计算反转计数。 
3. 如果反转计数为零，则最大值在当前范围的右半部分，包括$m$，因为没有元素大于该子数组中的最后一个元素。 
4. 否则，最大值必须在范围的左半部分，不包括后面的元素$m$这会产生反转。 
5. 递归地重复这种二分搜索式的缩小范围，直到搜索范围缩小到单个索引。 
6. 输出该索引作为最大元素的位置。 

工作原理：在每一步中，反转计数都会对数组进行分区。 右端的零反转保证了子数组中最右边的元素是最大的。 非零反转表示中点左侧存在更大的元素。 这个不变量确保我们在分而治之的步骤中永远不会排除真正的最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import math

def find_max_index(n):
    l, r = 1, n
    while l < r:
        mid = (l + r) // 2
        print(f"? {mid} {r}")
        sys.stdout.flush()
        inv = int(input())
        if inv == 0:
            l = mid
        else:
            r = mid - 1
    print(f"! {l}")
    sys.stdout.flush()

t = int(input())
for _ in range(t):
    n = int(input())
    find_max_index(n)
```该解决方案使用标准输入/输出和刷新来解决交互式问题。 这`find_max_index`函数维持一个搜索范围`[l, r]`。 中点查询确保成本与子数组长度的平方成正比，但二分搜索使总成本低于$5 \cdot n^2$限制。 特别关注`l < r`并更新`l = mid`相对`r = mid - 1`以避免无限循环或跳过元素。

 ## 边缘情况

 对于长度为 2 的排列，`[2,1]`, 查询`? 1 2`返回 1 个反转。 我们的算法将此解释为最大值位于索引 1 处。如果最大值位于索引 2 处，则查询将返回 0 个反转。 这证实了即使是最小的情况也能得到正确处理。 类似地，如果最大值位于较长排列的末尾，则从中点到末尾的查询会产生零反转，从而将搜索引导到右半部分并正确识别最后一个索引。 二分查找不变式也保证了所有其他位置的正确性。
