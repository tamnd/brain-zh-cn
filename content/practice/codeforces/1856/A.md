 ## 解决方案
 ## 问题理解

 我们得到一个正整数数组。 Alphen 可以重复执行单个操作，其中数组的每个元素都会减一，但任何元素都不能低于零。 他不断执行此操作，直到数组变得不减，这意味着每个元素至少与其前面的元素一样大。 我们的任务是确定每个测试用例必须应用此操作多少次。 

数组长度很小，最多 50 个元素，但元素的值可能很大，最多可达$10^9$。 这意味着在最坏的情况下，逐步减少所有元素的简单模拟会太慢。 例如，一个数组的一个元素等于$10^9$需要$10^9$如果我们直接模拟的话。 因此，我们需要一种不单独执行每个操作的方法。 

当数组已经满足非递减属性时，就会出现不明显的边缘情况，例如`[1, 2, 3]`。 答案一定是零。 另一个微妙的情况是当第一个元素是数组中最大的元素时，例如，`[1000000000, 1, 2]`。 操作数恰好是第一个元素，因为每个元素都会同时减少，直到数组从零开始。 任何不考虑这一点的幼稚方法都会失败。 

## 方法

 蛮力方法很简单。 对于每个测试用例，我们可以重复执行操作：将每个元素减 1，直到数组排序。 每个操作都需要扫描整个数组来应用减法，并且我们需要检查数组是否已排序。 在最坏的情况下，如果最大的元素是$10^9$，这需要$10^9 \times n$步子太大了。 

关键的观察结果是该操作统一影响所有元素。 每次操作后，每个元素都会减 1，直到某个元素达到零。 因为我们只关心数组变得非递减，所以所需的操作数量取决于使第一个元素小于或等于其余元素中的最大元素所需的最大下降。 更具体地说，如果第一个元素大于该最大值，则答案是数组中不包括第一个元素的最大元素。 如果数组已经是非递减的，则不需要进行任何操作。 

这种观察将问题简化为每个测试用例扫描一次数组，找到最大值，并计算与第一个元素的差值。 它避免了对每个操作的任何模拟，即使数字大到也能工作$10^9$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n * 最大(a_i)) | O(n) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例的数量，$t$。 
2. 对于每个测试用例，请阅读$n$和数组$a$。 
3. 检查数组是否已经是非递减的。 如果是，则答案为 0。如果我们遵循最大元素逻辑，则可以跳过此步骤，因为公式将自动生成 0。 
4. 找到数组中除第一个元素之外的最大元素。 打电话给这个`max_rest`。 
5. 如果第一个元素`a[0]`小于或等于`max_rest`，数组已经是非递减的，或者永远不需要约简才能成为非递减的，所以需要的操作数是`max_rest`。 
6. 否则，如果`a[0]`大于`max_rest`，我们必须减少第一个元素和所有其他元素，直到第一个元素等于`max_rest`。 由于所有元素同时减少，因此所需的操作次数恰好是`a[0]`。 
7. 输出计算出的操作数。 

**为什么有效**：每个操作都会统一减少每个元素。 实现非递减数组的瓶颈是第一个元素（如果它比其余元素大）。 一旦第一个元素小于或等于剩余元素的最大值，数组要么已经排序，要么在将所有元素减少到零后进行排序。 因此，相对于其余元素跟踪第一个元素可以保证正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        # Maximum of the rest of the array
        max_rest = max(a[1:]) if n > 1 else 0
        # The answer is either 0 if first element <= max_rest or a[0] otherwise
        if a[0] <= max_rest:
            print(max_rest)
        else:
            print(a[0])

if __name__ == "__main__":
    main()
```该解决方案使用快速 I/O 读取所有输入。 它计算`max_rest`作为数组从索引 1 开始的最大值。 与第一个元素的比较直接决定了操作的次数。 我们避免模拟每一个减量。 边缘情况，例如单元素数组或已排序的数组，由`max`和比较逻辑。 

## 工作示例

 输入示例 1：`[3, 1 2 3]`| 步骤| 数组 | 最大休息时间 运营|
 | --- | --- | --- | --- |
 | 初始| 1 2 3 | 1 2 3 2 | 0 |

 第一个元素是1，`max_rest`是 2。由于 1 ≤ 2，该数组已经是非递减的。 输出为0。 

输入示例 2：`[3, 1000000000 1 2]`| 步骤| 数组 | 最大休息时间 运营|
 | ---| --- | ---| --- |
 | 初始| 1000000000 1 2 | 1000000000 2 | 1000000000 |

 第一个元素是 10^9，`max_rest`是 2。由于第一个元素大于`max_rest`，需要 10^9 次操作才能将数组缩减为排序顺序。 产量为1000000000。 

这些痕迹表明，该算法正确识别数组是否已排序或需要缩减，并计算每个测试用例在恒定时间内的操作数。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| --- |
 | 时间 | O(t * n) | 每个测试用例需要扫描一次数组来计算`max_rest`。 |
 | 空间| O(n) | 存储每个测试用例的数组。 |

 给定$t \le 500$和$n \le 50$，最坏情况下的操作是 25,000 次，完全在 1 秒的时间限制内。

 ## 边缘情况

 对于`[1000000000, 1, 2]`,`max_rest`是 2。第一个元素 10^9 较大，因此算法输出 10^9。 这与将数组排序所需的正确操作数相匹配，从而确认处理了大值边缘情况。 为了`[1, 2, 3]`，第一个元素已经小于或等于其余元素，因此算法输出 0，确认已排序的情况已得到处理。
