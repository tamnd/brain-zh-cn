 ## 解决方案
 ## 问题理解

 我们得到一个整数网格，其中每一行代表一组选择，并且我们必须从每一行中恰好选择一个数字。 每行选择一个数字后，我们计算所有选定数字的按位异或。 任务是确定我们是否可以使此 XOR 严格为正，如果是，则输出实现此目的的任何有效列选择。 

关键对象不是网格本身，而是行选择集。 每一行只贡献一个值，最终结果取决于这些值在 XOR 下如何交互。 

约束足够小以允许$O(nm)$甚至$O(nm \log m)$每行推理。 和$n, m \le 500$，总共 250,000 个元素是可管理的，因此我们可以检查每一行并为每行做出简单的本地决策，而不是探索所有组合，这将是指数级的$n$。 

主要的微妙情况是矩阵中的所有数字都为零。 那么每个可能的选择都会产生 XOR 等于 0 的结果，因此答案必定是不可能的。 一个不太明显的情况是所有行仅包含相同的值，例如每行都是`[7, 7, 7]`。 即使这样，任何选择都会产生 XOR 等于$7 \oplus 7 \oplus \cdots$，根据行的奇偶校验，它仍然可能变为零，并且结构比单个行更重要。 

一个天真的错误是认为我们可以贪婪地选择任何存在的非零元素。 这会失败，因为 XOR 是全局的：非零元素稍后可以与其他元素抵消。 正确的推理必须确保我们故意强制至少有一位在最终的异或中幸存。 

## 方法

 强力解决方案会尝试每一种选择每行一个元素的方法。 那是$m^n$的组合，即使对于$n = 20$。 它正确的原因很简单：它直接检查所有可能的 XOR 结果并验证是否有一个非零。 故障点是组合爆炸。 

我们需要使用 XOR 结构来压缩问题。 XOR 在位上是线性的，因为如果最终结果为零，则每个位都会在行之间抵消。 这表明我们应该避免探索完整的组合，而是确保至少一位位置变得不平衡。 

关键的观察非常简单：如果每一行都包含至少一个非零元素，我们总是可以通过确保至少一行贡献一个改变所选位的值来构造一个产生非零异或的选择。 唯一真正不可能的情况是矩阵中的每个元素都为零。 

我们可以通过首先选择任意基线选择来利用这一点，通常从每一行中取出第一列，然后计算异或。 如果它已经非零，我们就完成了。 如果它为零，我们尝试通过将一行恰好更改为产生不同值的不同列来修复它，除非该行是常量，否则该值必须存在。 

这将问题简化为查找替代选择更改 XOR 状态的一行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(m^n)$|$O(n)$| 太慢了|
 | 建设性基线+修复|$O(nm)$|$O(n)$| 已接受 |

 ## 算法演练

 我们构建一个简单的候选解决方案，并在需要时对其进行修复。 

1. 首先选择每行的第一列。 这立即给出了有效的完整选择，并让我们计算初始异或。 
2. 计算所有选定值的 XOR。 如果这个异或非零，则当前选择已经满足条件，我们可以直接输出它。 
3. 如果 XOR 为零，我们需要以改变最终 XOR 的方式修改选择。 
4. 逐行扫描，检查该行中是否存在与当前选择的值不同的列。 
5. 如果我们找到这样的行，我们会将其选择切换到该不同的列。 这保证了异或从零变为非零，因为翻转零异或配置中的一个值必须引入非零差异。 
6. 输出更新后的选择。 

第 5 步起作用的原因是，当总 XOR 为零时，替换一个值$x$具有另一个值$y$将 XOR 更改为$x \oplus y$，如果$x \ne y$。 这立即打破了零状态。 

### 为什么它有效

 如果所有行在所有列中都具有相同的值，则无论选择如何，每行都会贡献相同的数字，因此 XOR 是固定的并且等于 XOR 后的数字$n$次。 如果该数字为零，则不可能进行任何更改。 否则，当以下情况时，初始 XOR 已经非零：$n$为奇数，或为零时$n$是偶数，但在这种情况下，每一行都是恒定的，因此不存在修改来改变结果。 因此，该算法仅在全零矩阵情况下完全失败，这正确地产生“NIE”。 在所有其他情况下，至少一行包含不同的值，允许单次翻转强制执行非零异或。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    choice = [0] * n
    x = 0

    for i in range(n):
        choice[i] = 0
        x ^= a[i][0]

    if x != 0:
        print("TAK")
        print(*[c + 1 for c in choice])
        return

    for i in range(n):
        base = a[i][0]
        for j in range(1, m):
            if a[i][j] != base:
                choice[i] = j
                x ^= a[i][0]
                x ^= a[i][j]
                print("TAK")
                print(*[c + 1 for c in choice])
                return

    print("NIE")

if __name__ == "__main__":
    solve()
```构造从固定的基线选择开始，使异或计算变得简单。 修复阶段只仔细更改一行，确保我们可以在本地推理 XOR 差异。 更新内容`x ^= old ^ new`反映了替换异或和中的一个元素的精确代数效应。 

对不同元素的内部扫描是安全的，因为如果成功，它保证对 XOR 进行非零调整。

 ## 边缘情况

 最微妙的情况是每行都包含相同的值。 在这种情况下，更改列没有任何作用，因此唯一的决定因素是奇偶性和值一致性。 如果重复值为零，则不存在解，因为每个 XOR 都被迫为零。 如果它不为零，则初始 XOR 已经固定，并且可能为零也可能不为零，具体取决于奇偶校验，但无法更改它，因此正确性完全取决于检测任何行是否具有不同的替代值。 

另一个微妙的情况是，即使矩阵中存在非零元素，初始 XOR 也为零。 该算法通过强制单行修改来处理此问题，这已经足够了，因为异或更改是本地化的，并且当值不同时保证非零。
