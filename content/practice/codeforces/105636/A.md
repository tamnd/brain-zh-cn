 ## 解决方案
 ## 问题理解

 我们有两个长度相等的二进制字符串。 有些位置被标记为可移动，有些则被锁定。 

移动包括交换两个相邻的角色，但只有允许参与交换的角色才可以移动。 由于交换是相邻的并且可以重复任意多次，因此标记的每个最大连续位置段`1`掩码中的行为就像一个可自由排列的块。 角色无法越过锁定位置。 

在对任一字符串执行任意次数的此类交换后，我们希望最大化两个最终字符串包含相同字符的位置数量。 

每个字符串的长度可以达到$10^5$，并且有多个测试用例。 任何重复模拟交换或尝试不同重新排列的解决方案都会立即被排除。 我们需要每个测试用例接近线性时间。 一个$O(n^2)$方法需要围绕$10^{10}$最坏情况下的操作，远远超出了极限。 

主要的微妙之处在于可移动角色并不是全球免费的。 角色只能在其自己的最大可移动位置段内移动。 由锁定位置分开的两个部分是完全独立的。 

考虑一个简单的例子：```
s1 = 01
s2 = 10
t1 = 11
t2 = 00
```第二根弦是固定的。 第一个字符串可以重新排列其两个字符。 通过移动`1`to the first position we obtain two matches. 单独处理可移动位置会错过这种可能性。 

另一个容易犯的错误是允许角色跨越锁定位置：```
s1 = 101
t1 = 101
```中间位置被锁定。 两个可移动位置属于不同的段，因此两个`1`不能通过中心交换位置。 

## 方法

 蛮力的想法是显式生成两个字符串的所有可达排列并检查相等位置的最大数量。 在可移动的长度段内$k$，任何排列都是可达的，因此状态数量呈阶乘增长。 即使长度为 15 的线段也已经超过$10^{12}$排列。 这种方法是没有希望的。 

关键的观察是，在可移动段内，只有`0`和`1`事情。 确切的顺序无关紧要，因为可以生成任何顺序。 

我们首先将每个字符串分解为组件。 

锁定头寸形成大小为 1 的组成部分，其值永远固定。 

具有掩码值的最大连续位置`1`形成可移动部件。 在这样的组件内部我们只需要知道有多少个`0`s 和多少`1`可用。 

现在考虑一个位置，一侧是固定的，另一侧属于可移动组件。 如果可移动组件仍然包含所需的数字，则此处匹配总是有益的。 一场比赛对答案的贡献恰好为 1，并且现在使用角色不能减少未来可能的最大贡献，因为每个角色最多只能贡献一次。 

所以我们贪婪地处理至少一侧固定的所有位置。 每当可移动组件可以提供所需的数字时，我们就会消耗一次出现并计数匹配。 

之后，就只剩下双方都可以移动的位置了。 在这样的位置，如果两个对应的分量仍然都包含`0`，我们可以匹配一个`0`这里。 否则，如果两者仍然包含`1`，我们可以匹配一个`1`。 如果两边都不存在数字，则该位置永远不可能相等。 

每个组件中的剩余计数完全描述了未使用的字符，因此尽可能贪婪地创建匹配是最佳的。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 太慢了|
 | 具有组件的最优贪婪 | O(n) | O(n) | 已接受 |

 ## 算法演练

 ### 步骤 1

 为两个字符串构建组件 ID。 

锁定位置有其自己的组成部分。 

可移动头寸的最大连续运行共享一个组件 ID。 

对于每个可移动组件，存储有多少个`0`s 和多少`1`它当前包含。 

### 步骤 2

 处理每个位置。 

如果两个位置都被锁定，它们的值将永远固定。 如果数字已经相等，则在答案中加一。 

如果第一面已锁定且第二面可移动，请检查第二部分是否仍包含所需的数字。 如果是，则消耗一次出现并向答案添加 1。 

如果第二侧已锁定且第一侧可移动，则进行对称操作。 

首先这样做的原因是固定头寸只有一个可能的值。 如果可移动组件能够满足该值，那么立即进行匹配不会有什么坏处。 

### 步骤 3

 再次处理每个位置。 

仅考虑两侧均可移动的位置。 

设相应的可动部件为$A$和$B$。 

如果两者仍然包含`0`，消耗一个`0`从每个并为答案加一。 

否则，如果两者仍然包含`1`，消耗一个`1`从每个并为答案加一。 

否则该位置不可能有匹配。 

### 步骤 4

 输出累计答案。 

### 为什么它有效

 每个可移动组件都完全由剩余数量来表征`0`和`1`。 

当位置涉及固定字符时，任何成功的匹配都必须使用可移动一侧出现的该固定数字一次。 延迟这场比赛不会带来任何好处，因为消耗的角色在任何地方最多只能贡献一场比赛。 

当所有固定位置需求都得到尽可能满足后，剩余的每个位置都有两个可移动的边。 在这样的位置上的匹配仅要求两个组件仍然具有相同的数字。 如果存在共同数字，则进行该匹配会立即消耗每一侧的一个字符并将答案增加 1。 未来的安排无法从这两个消耗的角色中提取多于一项的贡献。 

因此，每个贪婪匹配都是局部最优的，并且永远不会减少未来匹配的最大可实现数量。 重复这个过程会产生全局最优答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())

    for _ in range(T):
        n = int(input())
        s1 = input().strip()
        s2 = input().strip()
        t1 = input().strip()
        t2 = input().strip()

        comp1 = [-1] * n
        comp2 = [-1] * n

        cnt1 = []
        cnt2 = []

        cid = 0
        i = 0
        while i < n:
            if t1[i] == '0':
                comp1[i] = -1
                i += 1
            else:
                cnt1.append([0, 0])
                j = i
                while j < n and t1[j] == '1':
                    comp1[j] = cid
                    cnt1[cid][int(s1[j])] += 1
                    j += 1
                cid += 1
                i = j

        cid = 0
        i = 0
        while i < n:
            if t2[i] == '0':
                comp2[i] = -1
                i += 1
            else:
                cnt2.append([0, 0])
                j = i
                while j < n and t2[j] == '1':
                    comp2[j] = cid
                    cnt2[cid][int(s2[j])] += 1
                    j += 1
                cid += 1
                i = j

        ans = 0

        for i in range(n):
            a_fixed = (t1[i] == '0')
            b_fixed = (t2[i] == '0')

            if a_fixed and b_fixed:
                if s1[i] == s2[i]:
                    ans += 1

            elif a_fixed and not b_fixed:
                need = int(s1[i])
                c = comp2[i]
                if cnt2[c][need] > 0:
                    cnt2[c][need] -= 1
                    ans += 1

            elif not a_fixed and b_fixed:
                need = int(s2[i])
                c = comp1[i]
                if cnt1[c][need] > 0:
                    cnt1[c][need] -= 1
                    ans += 1

        for i in range(n):
            if t1[i] == '1' and t2[i] == '1':
                c1 = comp1[i]
                c2 = comp2[i]

                if cnt1[c1][0] > 0 and cnt2[c2][0] > 0:
                    cnt1[c1][0] -= 1
                    cnt2[c2][0] -= 1
                    ans += 1
                elif cnt1[c1][1] > 0 and cnt2[c2][1] > 0:
                    cnt1[c1][1] -= 1
                    cnt2[c2][1] -= 1
                    ans += 1

        print(ans)

solve()
```第一阶段构建可移动组件并记录有多少个`0`沙`1`每个组件包含。 

第二阶段处理涉及至少一个固定字符的每个位置。 这些匹配是最受限制的，因为固定方无法更改值。 

第三阶段处理双方均可移动的位置。 此时，所有剩余计数对应于尚未提交到固定位置匹配的字符。 

该实现使用组件 id 在恒定时间内访问正确的计数数组。 每个位置仅被访问几次，给出线性复杂度。

 ## 边缘情况

 考虑：```

3

```第一弦的中间位置被锁定。 这两个可移动位置属于不同的部件。

现在考虑：```
