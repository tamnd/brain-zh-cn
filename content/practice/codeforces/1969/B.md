 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，并允许重复“旋转”任何选定的连续段。 旋转将所选段的最后一个字符移动到其前面，将其余字符向右移动一个位置。 每个此类操作的成本恰好等于所选段的长度。 目标是将字符串转换为非递减的二进制字符串，这意味着使用总成本最小的操作，所有零必须出现在所有1之前。 

所以最终目标始终是以下形式的字符串`000...111...`。 我们并不是试图任意重新排列，只是通过子串的循环移位，并且每个动作的成本与我们接触的段的大小成正比。 

测试用例总长度的约束是$2 \cdot 10^5$，这会立即排除每个测试用例解决方案的任何二次方。 任何重复模拟操作或尝试所有子字符串的策略都会太慢。 我们需要每个测试用例更接近线性的东西。 

不明显的困难是轮换不是简单的交换或移动。 它可以移动一个`1`向左穿过一块`0`s，但仅限于所选段内，并且无论钻头有效移动多远，都会花费整个段长度。 

一些边缘情况揭示了天真的直觉失败的地方：

 如果字符串已经排序，例如`000111`，答案为零，因为任何操作只会增加成本。 正确的解决办法必须避免做不必要的举动。 

如果字符串是`10`，对整个字符串进行一次操作即可`01`成本为 2，这是最优的。 任何“本地修复”的尝试总体上都会花费更多。 

如果字符串是`1010`，贪婪的相邻修复很容易过度计算，因为单个旋转可以处理多个局部反转结构，但仍然会产生全局成本。 

这些案例表明，问题不在于直接计算反转，而在于理解旋转如何摊销运动。 

## 方法

 暴力策略将尝试模拟该过程。 在每一步中，它都可以尝试每个子字符串，应用旋转，并递归计算完成排序的成本。 即使进行了修剪，这种情况也会爆炸，因为有$O(n^2)$每个配置的子字符串和可能的许多步骤。 状态空间实际上是通过子串旋转可到达的所有排列，它太大了。 

关键的观察是我们永远不需要模拟任意的重新排列。 最终的结构是固定的，所以每一个`1`最终位于 a 的左侧`0`必须“跨越”至少一个反转边界。 唯一有意义的结构是零和一之间的边界，以及有多少个`1`s 被错误地放置在该边界之前。 

查看操作的更有用的方法是旋转一段长度$k$可以以成本为代价将一个元素从段的末尾移动到前面$k$。 如果我们仔细选择段，每个操作都会有效地“支付”在不匹配的位上移动块边界的费用。 最佳策略分解为处理相同字符的连续块，并根据我们必须“合并”交替运行的次数来支付成本。 

具体来说，字符串可以看作是这样的`000...0111...100...`。 每个转变从`1`到`0`表示必须解决的错位。 最佳解决方案最终会为每个此类边界收取一次费用，并根据该段交互中涉及的角色数量进行加权。 这导致了线性扫描，每当`1`-到-`0`转换是在第一个之后遇到的`1`已经出现了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们扫描字符串，同时跟踪是否已经看到过`1`。 一旦我们看到一个`1`, 稍后`0`表示必须通过旋转将未来的结构“向左拉”的结构，并以累积超出边界的方式贡献答案。 

1.从左到右遍历字符串，同时保持一个flag`seen_one`，最初为假。 这个标志记录了我们是否已经进入了它们所在的区域。 
2.当我们遇到一个角色时`1`，我们设置`seen_one = true`。 这标志着后缀区域的开始，该后缀区域最终必须形成排序字符串的右侧部分。 
3.当我们遇到一个角色时`0`后`seen_one`是真的，我们在答案中添加成本贡献 1。 推理是，每个这样的零都代表一个错位的元素，它必须跨越至少一个 1 的边界，并且这些交叉在整个结构中累积。 
4. 返回累计成本。 

关键的想法是每个`0`在第一个之后`1`每次必要的结构性修正只贡献一次，并且轮换允许这些修正以最佳方式捆绑在一起，而无需为本地互换支付双重费用。 

### 为什么它有效

 不变的是一旦第一个`1`出现，随后的每个`0`位于该区域的“内部”，该区域最终将被推到最后一个块的左侧。 每个这样的零对应于至少一个跨过边界之间的边界的所需位移。`1`-块和一个`0`- 阻止最终安排。 贪婪累加精确地计算了这些不可避免的相互作用，而不会过度计算，因为无论旋转如何组合，每个有问题的零仅被充电一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        seen_one = False
        ans = 0
        
        for ch in s:
            if ch == '1':
                seen_one = True
            elif seen_one:
                ans += 1
        
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现是基于扫描的想法的直接转化。 我们维护的唯一状态是我们是否已经看到了`1`。 一旦发生这种情况，每个`0`增加答案。 重要的微妙之处在于我们永远不会重置`seen_one`，因为相关区域是由第一次出现定义的`1`。 

简单性隐藏了核心推理：我们不是模拟旋转，而是计算任何旋转序列必须解决的结构违规的数量。

 ## 边缘情况

 对于已经排序的字符串，例如`000111`，扫描从未遇到`0`在第一个之后`1`，所以答案始终为零。 这符合不需要任何操作的事实。 

对于像这样的字符串`111000`，第一个`1`立即出现，并且每个后续零贡献一次，产生的成本等于尾随零的数量。 这捕获了一个连续段中的完整反转块。 

对于交替模式，例如`101010`，该算法对第一个零之后出现的每个零进行计数。 每个这样的零都反映了局部旋转无法避免的结构违规，证实了贪婪积累是紧的。
