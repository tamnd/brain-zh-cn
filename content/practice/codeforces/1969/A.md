 ## 解决方案
 ## 问题理解

 每个朋友都被指定了另外一个朋友作为他们的“最好的朋友”，并且这个分配形成了大小的排列$n$。 关键规则是，只有当朋友和他们指定的最好的朋友都受到邀请时，朋友才会参加聚会。 

这将创建一个依赖图，其中每个顶点都恰好有一个出边，并且每个节点也恰好有一个入边。 因此，该结构是有向循环的不相交并集。 每个循环代表一组相互依赖的封闭组。 

我们可以向任何朋友组发送邀请。 在被邀请的人中，只有一些人会真正出现：朋友$i$仅当两者都出现在最终出席人数中时$i$和$p_i$都在受邀集合中。 目标是确保至少有两个朋友最终参加，同时尽量减少发送的邀请数量。 

约束很小，有$n \le 50$，因此即使每个测试用例的三次或指数推理也是可以接受的。 但是，测试用例的数量可能很大，最多可达 5000 个，因此每个测试用例的解决方案必须是线性或接近线性的。 

一个天真的但重要的失败案例来自于假设邀请两个朋友总是足够的。 考虑一个 4 周期的$1 \to 2 \to 3 \to 4 \to 1$。 如果我们只邀请两个互不为好友的节点，比如 1 和 2，则没有人参加，因为 1 需要 2，2 需要 3。所以实际出席人数为空。 这说明“邀请两个人”并不等于“邀请两个人”。 

另一个微妙的情况是存在 2 个周期时。 例如$1 \leftrightarrow 2$。 只需邀请 1 和 2 人就足够了，两人都参加。 这表明小周期的行为与长周期的行为不同，而周期结构是问题的核心。 

## 方法

 蛮力的想法是尝试受邀朋友的每个子集，模拟谁参加，并选择产生至少两个参加者的最小子集。 对于每个子集，我们检查每个朋友，看看他们和他们最好的朋友是否都在场。 这是$O(2^n \cdot n)$，即使对于$n = 50$， 自从$2^{50}$是一个天文数字。 

关键的观察结果是，出勤率完全由排列中的周期决定。 由于每个节点恰好指向另一个节点，并且所有节点都是不同的，因此该图分解为循环。 在一个周期内，出席率受到该周期相邻的限制。 

对于长度为 2 的周期，邀请两个节点会立即产生 2 个与会者。 对于长度大于 2 的任何周期，单个受邀节点不会传播出席情况，因为它的邻居也必须受到邀请，并且该邻居依赖于另一个节点，从而创建一条链，除非考虑整个周期，否则无法关闭。 

关键的简化是，答案仅取决于最小的周期大小，但有一个特殊的区别：2 个周期给出答案 2，而任何长度至少为 3 的周期允许我们通过邀请周期中的任何 3 个连续节点来获得 2 个与会者。 这确保了两个相邻依赖关系同时得到满足的链。 

因此，问题简化为找到所有周期长度并采取尽可能最小的方式产生至少两名参与者，这将变为 2（如果存在任何 2 周期）或 3。

 | --- | --- | --- | --- |
 | 对子集的暴力破解 |$O(2^n \cdot n)$|$O(n)$| 太慢了 |

 ## 算法演练

 我们独立处理每个测试用例并提取排列周期。 

1.构建一个大小为visited的数组$n$，最初都是假的。 这确保我们不会重新访问已经分配给循环的节点。 
2. 迭代每个节点$i$。 如果没有被访问，则开始跟踪该链$i \to p_i \to p_{p_i} \to \dots$直到我们返回到访问过的节点。 所有遇到的节点形成一个循环。 标记他们访问过。 
3. 记录每个周期的长度。 这已经足够了，因为排列结构保证没有分支，因此每个节点恰好属于一个循环。 
4. 如果任何循环的长度恰好为 2，则立即返回 2。这是因为 2 循环允许通过恰好两个邀请（每个节点一个）来满足相互依赖性。 
5. 如果不存在 2 周期，则返回 3。任何更长的周期始终允许构建具有 3 个邀请的有效配置，从而产生至少两名与会者。 

正确性取决于这样一个事实：最好的朋友关系在长度为 2 的周期中是对称的。更长的周期需要打破依赖链，而产生出勤的最小稳定配置需要三个连续的节点。 

### 为什么它有效

 排列分解为独立的循环，并且出勤约束是局部的边缘。 2-cycle 是唯一两个节点可以在不涉及任何第三个节点的情况下彼此满足的结构。 每个长度至少为 3 的周期都会强制至少有一个中间依赖关系，因此两个邀请不足以保证两个与会者，除非周期本身的大小正好为 2。一旦排除所有 2 个周期，激活两个相邻依赖关系的最小构造需要三个节点，这在任何更长的周期内始终可以实现。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = [0] + list(map(int, input().split()))
        
        vis = [False] * (n + 1)
        has_two_cycle = False

        for i in range(1, n + 1):
            if not vis[i]:
                cur = i
                cycle = []
                while not vis[cur]:
                    vis[cur] = True
                    cycle.append(cur)
                    cur = p[cur]

                if len(cycle) == 2:
                    has_two_cycle = True

        if has_two_cycle:
            print(2)
        else:
            print(3)

if __name__ == "__main__":
    solve()
```代码直接实现了排列的循环分解。 该数组的索引为 1 以匹配问题定义，这样可以避免遵循时出现差一错误$p_i$。 每个循环通过步行收集，直到遇到先前访问过的节点，其长度仅用于检测是否存在2个循环。 答案仅取决于是否出现任何长度为 2 的循环。 

一个微妙的一点是，我们永远不需要明确地模拟邀请或出席。 周期结构完全决定了可行性，因此仅跟踪周期长度就足够了。

 这表明虽然存在 3 个周期，但 2 个周期的存在主导了答案。 一旦存在相互配对，仅邀请这两个人就会产生两名与会者，这是最佳的。

 输入：```

```| 起始节点 | 循环被发现| 周期长度| 发现 2 个周期 |

 ## 边缘情况

 一个关键的边缘情况是当排列完全由长于 2 的循环组成时。例如$1 \to 2 \to 3 \to 4 \to 1$。 该算法正确识别长度为 4 的单个周期，并且不设置 2 周期标志，从而产生输出 3。任何将邀请减少到 2 个的尝试都会失败，因为没有一对可以满足相互依赖性。 

另一种情况是存在多个周期且其中只有一个是2周期，例如$1 \leftrightarrow 2$和$3 \to 4 \to 5 \to 3$。 该算法检测到第一个组件中的 2 个周期，并立即得出答案为 2。这是正确的，因为周期是独立的，并且一个有效的对足以满足至少两个参与者的要求。 

最后一个微妙的情况是$n = 2$。 唯一可能的排列是 2 周期，因此答案始终是 2。算法自然地处理这个问题，无需特殊的大小写，因为周期检测逻辑直接标记​​长度为 2 的周期。
