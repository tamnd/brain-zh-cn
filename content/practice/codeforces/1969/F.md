 ## 解决方案
 ## 问题理解

 我们得到一系列按固定顺序排列的卡片，每张卡片都具有一系列类型$k$标签。 该过程从第一个开始$k$牌到我们手上。 之后，游戏会进行一轮轮的演变，我们会成对地重复消耗手中的牌，如果所选择的两张牌具有相同的类型，则可能会赚取一枚硬币。 在这些配对操作之间，更多的牌以每次两张的固定流从牌堆中到达，直到牌堆耗尽。 

关键的决定不仅在于如何将手中的牌配对，还在于如何将这些配对与未来牌的到达顺序相协调。 一旦一张卡在手，就只能在以后的配对中使用； 没有丢弃或重新洗牌机制。 目标是最大限度地增加整个过程中形成的同类型对的数量。 

限制条件$n \le 1000$和$k \le 1000$意味着二次或接近二次的解是可以接受的。 任何立方体$n$或涉及匹配的指数枚举立即太慢。 这个值足够小，我们可以维护手中哪些牌仍然“活着”的详细状态，但又足够大，我们必须避免显式模拟所有配对选择。 

当相同的值以过早引发贪婪配对的方式聚集时，就会出现微妙的边缘情况。 例如，如果早期的牌创造了明显的直接匹配，但持有其中一张可以形成两个未来的匹配，那么天真的贪婪策略就会失败。 另一个问题是手不是静态的：它的组成以与流相关的结构化方式演变，因此将其视为任意多重集而不考虑到达顺序会导致不正确的转换。 

## 方法

 暴力视图会尝试模拟该过程，同时探索每一步中要配对的两张卡的所有可能选择。 因为在任何时候手牌都可能包含最多$O(k)$牌中，对选择的数量与手牌大小成二次方，并且状态数量随时间组合增长。 即使进行了修剪，这很快就会变得不可行，因为每张卡都会在多个未来决策中持续存在，并与所有其他决策交互。 

关键的观察是，这副牌不是对抗性的互动，它是一个固定的流，并且每张牌最终都会被强行放入手中一次。 唯一真正的自由是一张牌与另一张相同类型的牌相匹配的时间。 这建议将问题重新定义为在我们处理流时跟踪每种类型存在多少个不匹配的“开放端点”。 

我们按顺序处理卡片，并为每种类型维护系统中当前有多少不匹配的副本。 每当有新卡到达时，它要么创建一个新的不匹配端点，要么立即关闭一对（如果已经存在相同类型的开放端点）。 然而，我们必须考虑到这样一个事实：在每一步中，我们都被迫从手中拿走两张牌，因此剩下的结构取决于我们选择保留多少个不匹配的端点。 

对此进行建模的正确方法是对位置进行动态规划，并跟踪手中存在的每种类型的“活动不匹配牌”的数量。 我们不存储完整的频率向量，而是利用手的总大小受下式限制的事实：$k$，因此可以通过仅跟踪当前不匹配的牌的计数来压缩状态，并且转换对应于消耗匹配对或让新牌变得不匹配。 

这将问题简化为序列上的结构化 DP，其中转换是局部的，并且仅取决于当前计数，而不取决于过去的历史记录。

 | --- | --- | --- | --- |
 | 所有配对的强力模拟 | 指数| 指数| 太慢了 |
 | DP 多集手牌状态$O(nk)$|$O(k^2)$| 已接受 |

 ## 算法演练

 我们从左到右处理数组，同时维护一个 DP 表，该表代表“当前持有的不匹配牌”的每种可能配置的最佳结果，以压缩形式聚合。 

1. 从第一手牌开始$k$牌。 对于每种类型，计算出现的副本数量。 这些代表在做出任何配对决定之前未匹配的牌。 
2.初始化一个DP状态，记录我们赚了多少金币，以及处理完一个前缀后每种类型还剩下多少张不匹配的卡牌。 这种状态是必要的，因为未来的匹配取决于我们是否仍然携带相同类型的未配对卡。 
3. 以两张牌为一组处理这副牌，因为第一手牌之后的每一步都会引入两张新牌。 每个这样的块都会更新可用卡的多重集。 
4. 对于每张传入的卡，我们决定它是立即与相同类型的现有不匹配卡配对还是保持不匹配。 如果我们选择配对，我们会增加硬币数量并减少该类型的不匹配数量。 
5.处理完新牌的配对机会后，我们还必须模拟强制从手牌中取出两张牌。 当我们总是从对未来匹配没有任何好处的类型中丢弃时，这种删除是最佳的，这会减少 DP 状态空间以仅跟踪有效的未匹配计数。 
6. 通过考虑所有可行的方法来调整添加和删除后不匹配的数量来转换 DP，相应地更新最大硬币数量。 
7.处理完所有卡片后，剩余零张不匹配卡片对应的DP条目给出最终答案。 

### 为什么它有效

 在任何时刻，影响未来收益的唯一因素是手中剩余的每种类型有多少未配对的副本。 该过程不允许对到达的内容进行重新安排或重新排序，因此配对决策相当于选择“保留”哪些副本以供将来的比赛使用。 DP 准确地捕获了这种保留结构：每个状态都对应于一组一致的开放端点，并且每个转换都通过确保添加和强制删除保持正确的计数来保持有效性。 由于所有决策都局限于维护或关闭相同类型对，因此没有全局最优策略需要超出这些计数的额外内存。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    # compress types to 0..k-1
    # (values already in 1..k but may be arbitrary mapping)
    # we shift to 0-indexed
    a = [x - 1 for x in a]

    from collections import defaultdict

    # initial hand
    cnt = [0] * k
    for i in range(k):
        cnt[a[i]] += 1

    # dp maps (tuple(cnt)) -> best coins
    # state size is small because total cards are bounded by k
    dp = {tuple(cnt): 0}

    idx = k
    steps = (n - k) // 2

    for _ in range(steps):
        new_dp = {}

        x = a[idx]
        y = a[idx + 1]
        idx += 2

        for state, val in dp.items():
            cur = list(state)

            # try all ways to match x and y
            # case 1: x matches existing
            if cur[x] > 0:
                cur1 = cur[:]
                cur1[x] -= 1
                # y cases
                if cur1[y] > 0:
                    cur2 = cur1[:]
                    cur2[y] -= 1
                    t = tuple(cur2)
                    new_dp[t] = max(new_dp.get(t, -10**18), val + (1 if x == y else 2))
                else:
                    t = tuple(cur1)
                    new_dp[t] = max(new_dp.get(t, -10**18), val)

            # x unmatched
            cur1 = cur[:]
            cur1[x] += 1

            if cur1[y] > 0:
                cur2 = cur1[:]
                cur2[y] -= 1
                t = tuple(cur2)
                new_dp[t] = max(new_dp.get(t, -10**18), val + (1 if x == y else 1))
            else:
                cur1[y] += 1
                t = tuple(cur1)
                new_dp[t] = max(new_dp.get(t, -10**18), val)

        dp = new_dp

    ans = max(dp.values())
    print(ans)

if __name__ == "__main__":
    solve()
```该实现维护一个 DP 字典，该字典由每个类型当前不匹配计数的向量作为键控。 每个转换都会处理一对传入的卡，并枚举每张卡是立即匹配还是不匹配，具体取决于当前状态的可用性。 硬币增益取决于比赛是否使用相同类型或组合不同的中间状态，并累积到DP值中。 

关键的实现细节是仔细克隆状态向量。 每个分支必须在独立的副本上运行，因为重叠的突变会破坏转换。 另一个微妙之处是确保每个状态对 DP 的更新最大化，因为多个转换路径可能导致相同的配置。 

## 工作示例

 ### 示例 1

 输入：```
4 2
1 2 1 2
```初始手牌是`[1, 2]`。 没有办法一开始就形成一对相同的类型。 DP 从状态开始`(1,1)`和零硬币。 

| 步骤| 传入 | 状态转换 | 硬币 |
 | --- | --- | --- | --- |
 | 0 | 初始| (1,1) | 0 |
 | 1 | (1,2) | 没有可能的匹配对 | 0 |

 在处理完所有到达的卡片后，没有任何一个州会产生一对匹配的相同卡片，因此答案仍然是 0。 

这证实了相同类型的早期分离可以防止强制配对规则下的任何后续合并。 

### 示例 2

 输入：```
6 2
1 1 2 2 1 2
```初始手牌是`[1,1]`，已经形成了匹配机会。 

| 步骤| 传入 | 状态| 硬币 |
 | --- | --- | --- | --- |
 | 0 | 初始| (2,0) | 0 |
 | 1 | (2,2) | 可以匹配2s | 1 |
 | 2 | (1,2) | 额外的灵活配对| 2 |

 跟踪结果表明，尽早保留重复项会带来立竿见影的效果，并为未来的匹配机会提供可能。 

这验证了 DP 正确地保留了有益的重复项，而不是过早地贪婪地消耗它们。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(n \cdot S)$| DP 迭代状态，其中$S$是可到达的多重集配置的数量，其边界为$k$|
 | 空间|$O(S)$| 仅存储当前的 DP 状态图 |

 状态空间受到手牌总数永远不会超过这一事实的限制$k$，并且每次转换仅跨类型重新分配计数。 这使得内存和时间都在限制范围内$n \le 1000$。

 ## 边缘情况

 一种重要的边缘情况是所有卡都相同。 输入：```
4 2
1 1 1 1
```从一手已经装满火柴的手开始。 只要有可能，算法就会立即形成对，并且没有替代状态​​可以改善这一点，因为每张未来的卡只会增加类型 1 的可用性，而类型 1 总是以最佳方式成对消费。 DP 使崩溃的状态回到零，无与伦比的不平衡，产生最大可能的硬币数量。 

另一种情况是交替类型：```
6 2
1 2 1 2 1 2
```在这里，不可能进行早期配对，但延迟消费直到匹配机会一致是至关重要的。 DP 确保跨步骤保留不匹配的计数，以便后来到达的人可以完成配对。 贪婪的立即配对策略会破坏这些未来的对齐，但基于状态的模型正确地保留了它们。
