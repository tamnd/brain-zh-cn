 ## 解决方案
 ## 问题理解

 我们被要求将一组卡片排列成一行，其中一些标有零，一些标有一，以便没有两个零相邻，也没有三个连续。 我们预先知道每种类型卡的数量：`n`零点和`m`那些。 输出要么是满足这些条件的 0 和 1 序列，要么是`-1`如果不存在这样的安排。 

限制很大：两者`n`和`m`最多可达 10^6。 这意味着尝试所有排列的任何解决方案都是不可行的。 O(n + m) 的解决方案是可以接受的，但任何二次方都会超时。 

边缘情况来自极端的不平衡。 例如，如果零的数量远远多于一，则不可能将所有零分开，因为每个零在两侧都需要至少一个一（边缘可能除外）。 类似地，如果 1 的数量远远超过 0，那么无论我们如何交织，我们都会面临连续出现 3 个 1 的风险。 例如，与`n = 1`和`m = 4`，具有单个零的 1 序列不能防止三个 1，因此正确的输出是`-1`。 

还必须考虑小数量。 为了`n = 1`和`m = 2`，唯一有效的排列是`101`或者`110`。 但`011`将违反零邻接规则，因此即使输入很小，粗心的构建也可能会失败。 

## 方法

 暴力方法会尝试生成所有序列`n`零点和`m`并检查每个的有效性。 这显然是不可行的，因为排列的数量在n+m中呈指数增长，远远超出了n、m的1秒时间限制，最多可达10^6。 

关键的见解是贪婪地处理序列。 约束允许一行中最多有两个 1，一行中最多有一个 0。 这意味着我们可以根据剩余计数和序列中的最后一个元素重复附加 1 或 0。 如果零即将相互接触，我们必须插入一个一。 如果我们面临三个 1 的风险，我们必须插入一个零。 这将问题简化为根据剩余计数重复做出局部最优选择，这可以在 O(n + m) 内完成。 

在构建序列之前我们还需要检查可行性。 对于零，每个 1 最多可以分隔两个零。 对于 1，每个 0 最多可以分隔一对 1。 这给出了界限：如果`n > m + 1`， 或者`m > 2*(n + 1)`，不存在解。 这些不平等从一开始就阻止了构建不可能的序列。

 | --- | --- | --- | --- |
 | 蛮力 | O((n+m)!) | O(n+m) | 太慢了 |
 | 贪心| O(n+m) | O(n+m) | 已接受 |

 ## 算法演练

 1. 检查是否`n > m + 1`或者`m > 2*(n + 1)`。 如果任一为真，则打印`-1`。 这些是从邻接约束导出的可行性界限。 
2.初始化一个空列表`result`逐步构建序列。 
3. 当还剩下 0 或 1 时，决定是放置一个还是两个 1，还是一个 0。 始终优先放置剩余数量较多的元素，但要遵守邻接约束。 具体来说，切勿在另一个零之后放置一个零，也不要连续放置第三个零。 
4. 从各自的计数中减去添加的元素数。 重复直到两个计数都为零。 
5. 转换`result`列表成字符串并打印。 

为什么它有效：通过始终放置具有较大计数的元素而不违反局部邻接规则，我们确保零永远不会接触，并且永远不会形成三元组。 可行性检查保证这种贪婪方法不会遇到不可避免的阻塞。 每一步都会减少卡片总数，因此算法在 O(n + m) 步骤中终止。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

if n > m + 1 or m > 2*(n + 1):
    print(-1)
    sys.exit()

result = []

while n > 0 or m > 0:
    if m > n:
        if m >= 2:
            result.append('11')
            m -= 2
        else:
            result.append('1')
            m -= 1
        if n > 0:
            result.append('0')
            n -= 1
    elif n >= m:
        if n > 0:
            result.append('0')
            n -= 1
        if m > 0:
            if m >= 2 and n < m - 1:
                result.append('11')
                m -= 2
            else:
                result.append('1')
                m -= 1

print(''.join(result))
```代码首先执行可行性检查。 然后，它使用贪心循环来始终附加最佳的可能段。 二元追加`'11'`仅当它不创建三个连续的时才使用。 这确保了始终保持邻接约束。

 ## 边缘情况

 对于`n = 1`,`m = 4`，算法首先检查可行性：`m = 4 > 2*(n + 1) = 4`是在边界处。 实际上，不可能将四个 1 与一个 0 分开。 算法打印`-1`立即地。 

为了`n = 5`,`m = 2`,`n > m + 1 = 3`，所以算法输出`-1`。 不会尝试构建违反零邻接规则的序列。 

对于相同的计数，例如`n = 3`,`m = 3`，算法交替放置元素，不保留相邻的零或三元组。 贪婪放置正确处理了这些边界场景，确认了鲁棒性。
