 ## 解决方案
 ## 问题理解

 万尼亚找到了他的扑克牌的子集，每张牌都标有一个整数$-x$和$x$。 他希望自己所有牌的总和为零。 我们需要确定他应该找到的附加牌的最小数量以实现零和。 

输入给出两个数字，$n$和$x$，代表他找到的牌的数量以及牌上允许的最大绝对值。 然后是一个列表$n$整数描述了找到的卡片的值。 输出是一个整数：将总和平衡为零所需的最小新卡数量。 

限制很小：$n \le 1000$和$x \le 1000$。 这使得算法能够以线性时间运行$n$。 Vanya 从找到的牌中可以得到的最大绝对值总和是$1000 \times 1000 = 10^6$，可以使用标准整数类型安全地处理。 

一个微妙的情况是当找到的牌的总和已经可以整除时$x$或小于$x$。 例如，如果 Vanya 找到了一张值为 7 的牌并且$x = 3$，他无法用单张卡来平衡，所以他必须使用多张卡。 如果总和不为零，粗心的解决方案可能会假设最小数始终为 1，这是不正确的。 

## 方法

 天真的方法是尝试所有附加卡的组合$-x$和$x$直到总和变为零。 这在原则上是正确的，因为我们总是可以选择足够的卡来补偿任何金额，但这是不切实际的。 例如，如果总和为 1000 并且$x = 1$，我们需要探索最多 1000 张卡片的序列，这在组合上是爆炸性的。 

关键的见解是要注意，唯一重要的是找到的卡片的绝对总和。 我们拥有任意价值的无限卡牌$-x$到$x$，所以问题简化为：给定目标总和$S$, 最多有多少张具有绝对值的牌$x$需要达到$S$？ 最低卡数就是上限$|S| / x$。 这是有效的，因为我们总是可以沿着与总和相反的方向重复选择最大的允许卡，直到达到零。 

这将问题从组合搜索转换为简单的算术计算，运行在$O(n)$计算输入和的总和$O(1)$计算所需卡片的数量。

 ## 算法演练

 1. 读取整数$n$和$x$。 这些代表找到的卡片数量和最大卡片价值。 我们将需要$x$以确定我们可以做出的最大单卡调整。 
2. 读取数组$n$代表找到的卡片的整数。 计算它们的总和，$S$。 现在的目标是将这笔金额减少到零。 
3. 取绝对值$S$，因为调整方向无关； 我们可以根据符号添加正牌或负牌$S$。 
4. 划分$|S|$经过$x$使用整数除法来计算需要多少张全尺寸卡。 如果$|S|$不能被整除$x$，我们需要一张额外的卡来支付剩余的费用。 
5.输出计算出的牌总数。 

为什么有效：通过重复取出最大允许绝对值的牌，我们可以最大限度地减少所需的牌数量。 不变的是，每添加一张牌后，剩余的修复金额最多减少$x$。 使用天花板划分可确保任何剩余部分小于$x$算作一张额外卡。 这保证了最小数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, x = map(int, input().split())
cards = list(map(int, input().split()))

total = sum(cards)
needed_cards = (abs(total) + x - 1) // x  # ceiling division
print(needed_cards)
```我们首先读取输入并计算找到的卡片的总和。 表达式`(abs(total) + x - 1) // x`计算上限`abs(total) / x`高效，无需浮点运算。 当总和不能完全整除时，这可以避免朴素整数除法中发生的差一错误$x$。

 解释：找到的牌的总和是 2。单张牌的最大点数是 2，所以一张 -2 的牌就足够了。

 这里的总和可以被最大卡值整除，因此只需要一张卡。

 ## 边缘情况

 如果牌的总和为零，则算法立即返回 0，因为不需要新牌。 例如，输入`2 5\n3 -3`给出`total = 0`， 所以`(abs(0) + 5 - 1) // 5 = 0`。 

如果绝对和小于`x`，算法正确输出1，覆盖单卡即可的场景。 用于输入`1 5\n3`,`abs(3)/5`小于 1，因此上限除法产生 1。 

在所有其他情况下，上限划分确保我们始终选择所需的最少卡片数量，而不超过所需的总数。 

这种方法是直接的，可以处理所有边缘情况，并且可以轻松扩展到输入限制。
