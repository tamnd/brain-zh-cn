 ## 问题理解

 我们得到一个由小写字符组成的字符串。 对于该字符串中的每个字符，我们可以将其保留为单个副本，也可以将其扩展为同一字符的两个连续副本。 这些选择是根据每个位置独立做出的，但字符的相对顺序永远不会改变。 

将这些选择应用于每个字符后，我们获得最终的扩展字符串。 在所有可能的扩展字符串中，我们想要字典顺序最小的一个。 

关键的困难在于一个位置的决定会影响最终字符串与其他有效结构的比较，因为复制或不复制都会改变字符的长度和本地排序。 

约束足够大，任何显式尝试所有加倍决策组合的方法都是不可行的。 由于每个字符都有两个选择，因此简单的搜索空间在字符串长度上呈指数级增长，即使对于中等大小（如 100000 个字符）也是不可能的。 这立即排除了暴力枚举或回溯。 

最重要的边缘情况来自于相同字符的运行以及字符值递增和递减之间的转换。 

例如，考虑一个像这样的字符串`abc`。 在`a`，除非我们知道如何复制，否则尚不清楚复制是否有帮助`b`行为。 如果我们在本地做出决定而不考虑未来的角色，我们可能会产生类似的东西`aabbcc`当存在较小的词典结果时，例如`abcc`或者`aabcc`取决于下游结构。 

另一个微妙的情况是当字符重复时，例如`aab`。 如果我们在每个位置独立决定，我们可能会重复第一个位置`a`但不是第二个，产生不一致的局部排序决策，这不是全局最优的。 

这些例子表明，位置决策`i`不能孤立地进行； 这取决于后缀的行为方式。 

## 方法

 暴力解决方案将尝试各种方法为每个字符分配一个副本或两个副本，构建结果字符串，然后按字典顺序取最小值。 对于一个长度的字符串`n`，这会产生`2^n`可能性，以及每个构建的字符串成本`O(n)`构建和比较。 这导致总体运行时间呈指数级增长，而这几乎立即变得不可行。 

关键的观察是我们永远不需要在全球范围内比较完整的结构。 相反，我们只需要了解在最终的词典比较中每个字符如何与下一个字符交互。 字典顺序是在两个结构不同的第一个位置决定的，因此唯一有意义的比较是原始字符串顺序中的相邻决定之间的比较。 

这使我们能够在本地进行推理，但以受控的方式：对于每个位置，我们根据它与实际值不同的下一个字符的比较来决定加倍是否有帮助。 相同的字符形成一个块，其中的决策必须保持一致，因为运行中的任何不匹配只会延迟比较而不改变相对顺序。 

这导致了从右到左的动态规则：每个位置的决策由下一个位置决定，通过字符串向后传播约束。

 ## 算法演练

 我们从右到左处理字符串，同时决定每个字符在最终答案中是否应该出现一次或两次。 

1. 从最后一个字符开始，强制其决策为单个出现，因为其后没有任何内容可供比较。 
2. 移至前一个字符并将其与原始字符串中的下一个字符进行比较。 如果当前字符小于下一个字符，则复制它可以改善字典顺序，因为它将较小的字符推到最终字符串的前面，从而使前缀更小。 
3. 如果当前字符比下一个字符大，则复制它会在最终字符串的前面插入一个更大的字符，这只会恶化字典顺序，因此我们将其保留为单个副本。 
4. 如果当前字符等于下一个字符，我们继承下一个位置的决策。 这是因为相同的字符形成依赖链，其中最佳结构必须在整个运行过程中保持一致； 任何偏差只会改变比较，而不会改进前缀排序。 
5. 计算完所有位置的决策后，根据计算的规则附加每个字符的一个或两个副本来构造最终字符串。 

微妙的部分是通过平等的字符进行传播。 如果没有它，局部比较就会失败，因为相等将真正的比较点隐藏在右侧。 

### 为什么它有效

 在每个位置`i`，构造的前缀仅在与第一个不同索引处的另一个有效构造进行比较时才有意义。 该决定于`i`仅当`s[i]`是两个候选输出之间的第一个分歧点。 如果`s[i]`等于`s[i+1]`，那么两个选择都将第一个分歧进一步向右推迟，这意味着最优决策完全由后缀决定。 这创建了一个稳定的向后依赖，其中每个位置从下一个不相等的比较点继承正确性，确保没有局部决策可以使全局词典最小性失效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    if n == 0:
        return

    # decision[i] = 1 or 2 copies of s[i]
    dec = [1] * n
    dec[n - 1] = 1

    for i in range(n - 2, -1, -1):
        if s[i] < s[i + 1]:
            dec[i] = 2
        elif s[i] > s[i + 1]:
            dec[i] = 1
        else:
            dec[i] = dec[i + 1]

    res = []
    for i in range(n):
        res.append(s[i] * dec[i])

    sys.stdout.write("".join(res))

if __name__ == "__main__":
    solve()
```解决方案首先读取字符串并准备一个数组`dec`存储每个字符是否应该出现一次或两次。 从右到左的循环对依赖逻辑进行编码：每个决策仅依赖于下一个字符或下一个已计算的决策，这确保了线性时间行为。 

构造阶段只是根据其存储的决策扩展每个字符。 除了确保最后一个字符始终正确初始化以及等字符传播使用之外，没有隐藏的极端情况`dec[i + 1]`而不是重新计算比较。

 ## 边缘情况

 对于单个字符输入，算法会立即分配单个字符，因为没有后缀可供比较。 这避免了后向循环中的任何边界问题。 

对于所有相同字符的字符串，例如`aaaa`，每个位置都继承最右边角色的决定。 由于最后一个字符是单个字符，因此整个链变成单个决策，从而不会导致加倍，这与当所有符号相同时加倍不会改变字典顺序的事实相匹配。 

对于像这样的递减字符串`cba`，每次比较都会产生单个副本。 该算法正确地避免了重复，因为每次本地比较都表明扩展会恶化字典顺序。 

对于像这样的递增字符串`abc`，每个字符都小于其后继字符，因此每个位置都加倍，产生一个大量前置的字典顺序最小字符串，确认最大化早期小字符是最佳的。
