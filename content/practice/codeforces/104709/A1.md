 ## 解决方案
 ## 问题理解

 我们得到一个源字符串和一个目标字符串。 可以通过从左到右处理源字符串将其转换为目标字符串，其中源中的每个字符都扩展为其自身的单个副本或自身的两个连续副本。 字符的顺序被保留，并且不允许重新排序或删除，只有这种受控的重复。 

任务是确定在该规则下是否可以从源字符串生成目标字符串。 换句话说，我们正在检查目标是否可以分为连续的块，其中每个块对应于源中的一个字符，每个块的长度为一或二，块内的所有字符都相同。 

输入大小足够小，线性扫描解决方案就足够了。 即使测试用例中字符串的总长度达到 10^5，每次测试的 O(n) 或整体 O(n) 策略也是安全的，而任何二次的都会太慢。 在每个字符上尝试“单”和“双”扩展的天真的回溯方法在最坏的情况下会呈指数级分支，一旦字符串长度超过几十，这种方法立即变得不可行。 

一些边缘情况在这里很重要。 如果目标比源短，则这是不可能的，因为每个源字符都会产生至少一个字符。 例如，来源`abc`和目标`ab`无法工作，因为即使是最小的扩展也已经产生了长度三。 另一种失败情况是假定块内的字符不匹配。 例如，来源`ab`和目标`aab`失败是因为消费后`a`，下一个源字符是`b`，但剩下的目标开始于`a`。 最后，当目标中的运行长度超过两个相同字符时，会出现一种微妙的情况。 例如，来源`a`和目标`aaa`无效，因为单个字符最多可以扩展为两个副本。 

## 方法

 暴力方法试图模拟每一种可能的扩展选择。 对于源字符串中的每个字符，我们递归地决定是将其映射到目标字符串中的一个字符还是两个字符。 这会在每一步创建高达 2 的分支因子，并且在最坏的情况下我们会探索 2^n 种可能性。 即使 n 约为 40，这也已经变得太慢，并且实际约束要大得多。 

关键的观察结果是结构是刚性的。 一旦我们固定了源字符串中的位置和目标字符串中的位置，匹配就不会出现歧义：我们被迫消耗目标中的一两个相同的字符。 这消除了任何回溯的需要。 我们可以使用两个指针贪婪地遍历两个字符串，将每个源字符与目标中的一个块进行匹配，并验证每个块的长度是 1 还是 2。 

蛮力之所以有效，是因为它探索了所有长度分配，但它失败了，因为大部分搜索都是多余的。 通过观察每个步骤都受到局部约束，我们可以将整个搜索折叠为单个线性传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们维护两个指针，一个用于源字符串，一个用于目标字符串，并在强制扩展规则的同时将它们向前移动。 

1. 两个指针都从各自字符串的开头开始。 这会将源的第一个字符与目标的开头对齐，因为不允许重新排序。 
2. 对于源中的当前字符，检查它是否与目标中的当前字符匹配。 如果不匹配，则无法立即进行转换，因为没有扩展规则会更改字符的身份。 
3. 计算当前源字符从目标指针开始在目标中连续出现的次数。 该游程长度决定了该源字符需要消耗多少个字符。 
4. 如果游程长度大于2或等于0，则配置无效。 游程为 0 意味着不匹配，游程大于 2 则违反了每个源字符最多扩展为两个副本的规则。 
5. 将目标指针向前移动我们消耗的游程长度，并将源指针移动一步，因为我们已经完全处理了该源字符。 
6. 重复此过程，直到处理完所有源字符。 最后，目标也必须被完全消耗掉； 否则，剩余的字符意味着额外的不匹配的扩展。 

正确性取决于每个源字符独立定义目标中的连续块，并且块大小受到严格限制。 

### 为什么它有效

 在任何时刻，该算法都保持不变，即当前源指针之前的所有字符都已与目标字符串中不相交的有效块相匹配，每个块的大小为一或二。 由于转换规则强制扩展不重叠并保持顺序，因此下一个有效块由当前目标位置唯一确定。 永远不会出现选择不同的分割可能导致稍后产生有效解决方案的情况，因为任何更长或更短的分配都会立即违反邻接或块长度约束。 这消除了搜索的需要，并保证了块的贪婪消耗是必要且充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can_transform(s, t):
    i = j = 0
    n, m = len(s), len(t)

    while i < n and j < m:
        if s[i] != t[j]:
            return False

        j_start = j
        while j < m and t[j] == s[i]:
            j += 1

        run_len = j - j_start
        if run_len == 0 or run_len > 2:
            return False

        i += 1

    return i == n and j == m

def solve():
    tcs = int(input())
    for _ in range(tcs):
        s = input().strip()
        t = input().strip()
        print("YES" if can_transform(s, t) else "NO")

if __name__ == "__main__":
    solve()
```实现的核心是两指针扫描。 内循环测量目标在仍然匹配当前源字符的情况下可以扩展多远，从而有效地计算扩展块的大小。 对游程长度的检查强制执行每个源字符最多贡献两个副本的规则。 

一个常见的陷阱是忘记在最后验证两个字符串的完全消耗。 即使所有字符都在本地匹配，目标中的剩余字符也表示无效的额外扩展。

 ## 边缘情况

 两个字符串都有长度的最小输入会检查基本转换。 如果`s = "a"`和`t = "a"`，该算法匹配游程长度 1 并干净地完成，确认单字符扩展是有效的。 

目标长度超过允许的情况，例如`s = "a"`和`t = "aaa"`，表明早期拒绝。 游程长度变为 3，这立即违反了约束，算法返回 false，无需继续。 

严格交替的情况，例如`s = "ab"`和`t = "abab"`，失败，因为运行不连续。 该算法的运行长度为一`a`，然后在期望时立即遇到不匹配`b`但发现`a`再次，正确拒绝交错扩展。
