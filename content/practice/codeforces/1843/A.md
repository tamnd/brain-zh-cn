 ## 解决方案
 ## 问题理解

 我们得到一个整数数组。 每个元素必须指定为一种颜色，并且我们可以使用任意数量的颜色。 

对于每种颜色，我们查看分配给该颜色的所有值。 它对总分的贡献是该组中最大值和最小值之间的差值。 目标是选择一种颜色，使这些贡献的总和最大化。 

元素的位置无关紧要。 颜色的成本仅取决于该颜色内部的值，因此在了解问题的结构之后，我们可以纯粹考虑数字的多重集。 

限制非常小。 每个测试用例最多包含 50 个数字，最多有 1000 个测试用例。 甚至一个$O(n^2)$或者$O(n^3)$解决方案将是完全安全的。 挑战不在于性能，而在于认识到隐藏在成本定义中的贪婪结构。 

一个常见的错误是认为将所有元素放入一种颜色总是最好的，因为这样会产生最大可能的范围。 考虑：```
4
1 3 6 9
```一种颜色的成本为$9 - 1 = 8$。 

更好的着色是：```
{1, 9}, {3, 6}
```这给出：```
(9 - 1) + (6 - 3) = 11
```另一个简单的陷阱是忘记单例组的贡献为零。 例如：```
1
5
```唯一可能的着色由包含值 5 的一组组成，因此答案是：```
5 - 5 = 0
```盲目地对值进行配对而不仔细处理奇数长度的解决方案可能会产生不正确的结果。 

具有所有相等值的数组也很重要：```
4
2 2 2 2
```每个组的最大值等于最小值，因此每个贡献都为零，并且无论颜色如何，答案都为零。 

## 方法

 暴力方法会尝试数组的所有可能的颜色并计算最终的成本。 这是正确的，因为它探索了元素与颜色的每一个有效分配。 

问题是着色的数量增长得非常快。 即使对于适度的值$n$，集合分区的数量变得巨大。 贝尔数字使得彻底的搜索变得不可行。 

为了找到更好的方法，我们需要了解影响分数的因素。 每个小组的贡献是：$$\max(\text{group}) - \min(\text{group})$$只有群体中最小和最大的元素才重要。 放置在它们之间的任何元素都不会影响该组的贡献。 

假设数组已排序：$$a_0 \le a_1 \le \dots \le a_{n-1}$$如果我们使用一些小值和一些大值创建一个组，那么贡献正是它们的差值。 为了最大化总和，我们希望最大的数字作为组最大值，最小的数字作为组最小值。 

最好的策略是重复将当前最大未使用值与当前最小未使用值配对。 每对这样的贡献：$$a_r - a_l$$在哪里$l$指向左端并且$r$指向已排序数组的右端。 

任何不成对的中间元素，当$n$是奇数，形成一个单例群并且贡献为零。 

排序后，答案变为：$$(a_{n-1}-a_0) + (a_{n-2}-a_1) + \cdots$$这自然就产生了两指针的解决方案。

 ## 算法演练

 1. 对数组进行非降序排序。 

排序后，最小值在左边，最大值在右边。 
2.初始化两个指针，`l = 0`和`r = n - 1`。 

这些指针代表最小和最大的未使用元素。 
3. 将答案初始化为零。 
4. 虽然`l < r`， 添加`a[r] - a[l]`到答案。 

这会将最大剩余值与最小剩余值配对，从这两个元素中提取最大可能的贡献。 
5. 移动`l`向右一步并且`r`还剩一步。 

这两个元素现在都已使用。 
6. 继续直至指针交叉。 

如果一个元素保留在中间，它将形成一种贡献为零的单一颜色。 
7. 输出累计答案。 

### 为什么它有效

 排序后，每个贡献都来自将充当组最小值的值与充当该组最大值的另一个值进行匹配。 

考虑任何最佳的着色。 整个数组的最大元素只能通过成为某个组的最大值来贡献。 为了最大化其贡献，它应该与最小的可用值配对。 使用更大的最小值只会减少差异。 

一旦最小和最大元素配对，相同的参数适用于其余元素。 反复匹配极值可以最大化每个提取的差异。 

这正好产生总和：$$(a_{n-1}-a_0)+(a_{n-2}-a_1)+\cdots$$这是任何着色所能实现的最大总成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        a.sort()

        l, r = 0, n - 1
        ans = 0

        while l < r:
            ans += a[r] - a[l]
            l += 1
            r -= 1

        print(ans)

if __name__ == "__main__":
    solve()
```第一步对数组进行排序。 排序后，最佳配对变得显而易见，因为最小和最大的未使用元素始终位于末尾。 

两个指针`l`和`r`从两端向内走。 每次迭代都会添加一个最佳对贡献。 由于两个端点在使用后立即被消耗，因此每个元素最多参与一对。 

条件`l < r`很重要。 什么时候`n`是奇数，中间一个元素保持未配对状态。 该元素对应于单一颜色并且贡献为零，因此不需要特殊处理。 

所有算术都适合 Python 整数。 尽管限制很小，但实施仍然高效且干净。

 ## 边缘情况

 考虑尽可能最小的输入：```
1
5
```排序后，数组仍然存在`[5]`。 指针从同一位置开始，因此循环永远不会运行。 答案保持为零，这与单一颜色贡献的事实相符`5 - 5 = 0`。 

考虑一个奇数长度的数组：```
5
1 2 3 4 5
```排序顺序不变。 该算法计算：```
(5 - 1) + (4 - 2) = 4 + 2 = 6
```价值`3`保持未配对状态。 它对应于贡献为零的单例组，完全符合要求。 

考虑所有相等的值：```
4
2 2 2 2
```该算法添加：```
(2 - 2) + (2 - 2) = 0
```每种可能的着色都具有零成本，因为每个组的最大值等于其最小值。 

考虑使用一种颜色不是最佳的情况：```
4
1 3 6 9
```一种颜色给出成本`9 - 1 = 8`。 

该算法计算：```
(9 - 1) + (6 - 3) = 11
```这证明了核心见解：将数字分成极端对可以产生比将所有数据分组在一起更大的总范围总和。
