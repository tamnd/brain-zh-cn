 ## 解决方案
 ## 问题理解

 我们得到了写在板上的整数数组。 游戏每轮重复删除两个数字，但顺序很重要：Alice 首先删除一个数字，目的是让 Bob 稍后无法形成良好的对，而 Bob 则通过删除另一个数字来做出响应，以尝试最大化两个删除值总和达到固定目标值的频率$k$。 每当一轮中选择的两个数字之和达到$k$，分数增加一。 

关键的困难在于玩家不合作。 Alice 正在积极尝试阻止 Bob 创建总和为$k$，而鲍勃则试图强制这样的配对。 最终得分仅取决于有多少轮最终形成互补对$(x, k-x)$。 

输入数据量很大，最多可达$2 \cdot 10^5$测试用例中的总元素。 这排除了对所有可能的游戏状态或递归游戏树推理的任何模拟。 任何试图评估每轮选择或跟踪分支结果的行为都会退化为二次行为，并且不会通过。 

当值正好是一半时，就会出现微妙的边缘情况$k$，因为配对需要两个相同的值。 例如，如果$k=10$而我们有很多5，那么每次成功的得分事件都会消耗两个5。 在这种情况下，将任意出现的值配对而不跟踪频率的天真贪婪很容易多计数或少计数。 

另一个边缘情况是当值形成重叠的互补链时。 例如，与$k=6$，像 1、2、4、5 这样的值相互作用，使得多个配对竞争相同的出现。 天真的“独立计数补充”方法会失败，因为它忽略了每个元素都被消耗一次。 

## 方法

 游戏的暴力解释将尝试模拟每个回合。 在每一步中，爱丽丝都会选择一个数字，鲍勃会做出最佳响应，然后我们递归地评估未来的结果。 这导致了深度分支博弈树$n/2$，并且在每个节点上最多有$O(n^2)$可能的选择。 即使使用记忆化，状态空间也取决于剩余数字的多重集，其大小呈指数级增长。 这远远超出了任何可行的限度。 

关键的观察是，对评分唯一重要的是鲍勃是否设法选择爱丽丝所选值的补数。 爱丽丝最好的防御是减少已经“危险”​​值的可用补充的数量。 鲍勃的最佳策略是保留或瞄准仍然有可用补充的价值。 

这种相互作用会分解为频率问题。 我们不是模拟转弯，而是考虑有多少不相交的对$(x, k-x)$可以在最优冲突下形成。 Alice 总是会试图通过提前中断潜在的匹配来“浪费”Bob 的机会，这实际上意味着每个值$x$仅与其补体竞争$k-x$，最终得分取决于有多少这样的对能够在最佳干扰下幸存下来。 

这导致了彻底的减少：我们计算所有值的频率，然后计算每个值的频率$x$，我们将其与$k-x$。 每个有效匹配都会消耗双方的一次出现。 需要特别注意的时候$x = k-x$，其中配对使用相同数字的两次出现。 

贪心实现变成：迭代值，始终匹配尽可能多的补数，确保每个数字最多使用一次。

 | --- | --- | --- | --- |
 | 暴力模拟| 指数| O(n) | 太慢了|
 | 频率贪婪匹配 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将游戏简化为计算在最佳游戏下可以从多重集合中形成多少个互补对。 

1. 构建数组中所有数字的频率图。 这让我们确切地知道每个值存在多少个副本，这是最优推理消除轮序复杂性后唯一相关的状态。 
2. 迭代每个不同的值$x$在频率图中。 对于每个值，计算其补码$y = k - x$。 我们只会对每对处理一次，以避免重复计算。 
3.如果$x < y$，我们尝试匹配出现的$x$与出现$y$。 贡献的有效评分对的数量为$\min(freq[x], freq[y])$。 然后，我们从概念上删除这些匹配的元素，以便它们无法参与其他地方。 
4. 如果$x = y$，我们处于自补的情况。 每个有效对需要出现两次$x$，所以贡献是$\lfloor freq[x] / 2 \rfloor$。 
5. 将所有贡献累加到最终分数中并输出给测试用例。 

订购条件$x < y$确保每对值仅处理一次，从而防止对称补码的重复计算。 

### 为什么它有效

 游戏简化为配对元素，只有互补的值才对得分起作用。 Alice的最优策略最多可以延迟或重新排列配对，但不能改变可以形成的不相交互补对的总数。 每个成功的分数恰好消耗两个值，总和为$k$，并且任何元素都不能贡献超过一个分数。 频率匹配过程构造最大数量的不相交有效对，这与最佳对抗性游戏下的结果相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        arr = list(map(int, input().split()))
        
        freq = {}
        for v in arr:
            freq[v] = freq.get(v, 0) + 1
        
        used = set()
        ans = 0
        
        for x in freq:
            y = k - x
            if x in used:
                continue
            if y not in freq:
                continue
            
            if x == y:
                ans += freq[x] // 2
            else:
                ans += min(freq[x], freq[y])
            
            used.add(x)
            used.add(y)
        
        print(ans)

if __name__ == "__main__":
    solve()
```解决方案首先计算每个值的出现次数，因为一旦我们推理出配对结构，各个位置就不再重要。 这`used`set 确保我们不会同时处理两者$x$和$k-x$分开，否则会重复计算对。 

案件分为`x == y`和`x != y`是必不可少的。 当值等于其补码时，配对是在单个存储桶内部进行的，因此我们除以二。 否则，我们使用最小操作来匹配两个频率桶。 

## 工作示例

 ### 示例 1

 输入：```
n = 4, k = 4
[1, 2, 3, 2]
```频率：

 1 → 1, 2 → 2, 3 → 1

 我们处理：

 | x| y = k-x | 频率[x] | 频率[y] | 贡献 |
 | --- | --- | --- | --- | --- |
 | 1 | 3 | 1 | 1 | 1 |
 | 2 | 2 | 2 | - | 1 |

 总分 = 2。 

这显示了交叉对 (1,3) 和自对 (2,2)。 自对情况很关键，因为它演示了为什么需要整数除以 2。 

### 示例 2

 输入：```
n = 6, k = 1
[1, 1, 1, 1, 1, 1]
```频率：1 → 6

 仅存在自补情况。 

| x| y | 频率[x] | 贡献 |
 | --- | --- | --- | --- |
 | 1 | 1 | 6 | 3 |

 总分 = 3。 

这证实了当所有值都相同时，每对消耗两个元素，并且不存在与其他值的交互。

 ## 边缘情况

 当所有值都相同且等于$k/2$，每个得分事件消耗两个相同的元素。 该算法通过整数除以二来处理这个问题，正确地反映了没有单个元素可以被重用。 

当值形成完美对称集时，例如$[1,2,3,4]$和$k=8$，每个值恰好有一个补码并且不会发生重叠。 频率配对确保每对都被计数一次，并且`used`设置可以防止重复。 

当没有两个值之和等于$k$，频率图仍然可以正确构建，但所有补集查找都会失败，导致贡献为零。
