 ## 解决方案
 ## 问题理解

 我们得到一个正整数数组。 我们可以重复选择两个相邻元素并执行“平衡减法”操作：我们查看一对，从两个条目中减去较小的值，然后继续。 此操作始终强制至少两个选定元素之一变为零，并且不会增加任何值。 

目标不是对数组进行完全排序，而是确定是否可以使用任意数量的此类操作将其转换为非递减序列。 

关键的困难在于操作是局部的，但它们的影响会传播：更改一对会影响未来调整相邻对的能力。 由于每个操作都保留非负性并且仅删除相邻对的质量，因此系统的行为就像我们在非常受限的规则下重新分配和擦除值一样。 

约束很严格：总计$n$所有测试用例的最大可达$2 \cdot 10^5$。 任何尝试模拟操作或探索数组状态的方法都会立即失败，因为每个操作都可以与邻居交互，并且可能的操作序列的数量呈指数增长。 这迫使我们对每个测试用例进行线性或近线性贪婪推理。 

当局部改进与全局排序发生冲突时，就会出现微妙的边缘情况。 例如，像这样的数组$[4, 5, 2, 3]$看起来几乎可以排序，但是操作结构阻止在不破坏早期结构的情况下修复中间块之间的反转。 另一个棘手的情况是交替高低模式，例如$[4,5,4,5,4,5,\dots]$，其中重复取消是否可以“平滑”序列并不明显。 最后，严格减少数组，例如$[4,3,2,1]$看起来它们可以通过重复减少来修复，但是该操作不能增加任何值，因此某些反转基本上是不可逆的。 

## 方法

 暴力方法将明确模拟所有可能的操作。 每个操作至少将涉及的两个元素之一减少为零，因此在最坏的情况下我们可能会执行$O(n^2)$操作，并且在每一步我们都需要搜索最佳的操作对。 即使我们将自己限制在固定的配对选择策略上，状态空间仍然会大量分支，因为每次减法都会改变未来的有效动作。 这在实践中很快就会呈指数级增长。 

关键的观察是，我们真正感兴趣的并不是确切的操作顺序，而是我们是否可以消除足够的“障碍”以使数组不减。 每个操作仅影响两个相邻位置，其唯一效果是将两个位置减少相同的量，可能使一个或两个位置都为零。 这意味着价值只能以一种非常可控的方式“向下流动”，而不能任意转移。 

关键的见解是从左到右处理阵列，为每个位置保持最小的可行“剩余容量”。 当我们固定前缀时，当前的值不能超过之前调整后的值所能支持的； 否则，任何操作序列都无法协调反转，因为我们无法增加较早的元素来进行补偿。 

这导致了贪婪的构造：我们模拟每个元素相对于前一个元素的最佳可能减少，确保在每一步，结果序列在其可实现的形式中保持不减少。 该操作本质上允许我们将相邻元素一起减少，因此有效约束变成调整后的前缀状态之间的比较而不是原始值。

 ## 算法演练

 正确的观点是，在与其左邻居进行所有优化操作后，每个位置都具有一些剩余的“可用价值”。 我们维护一个运行值，该值表示当前位置可以减少到的最小可能值，同时仍然允许有效的非减少延续。 

1. 从第一个元素开始不变，因为它前面没有任何东西来约束它。 这是前缀可实现的基线值。 
2. 对于每个下一个元素，将其与当前调整后的前一个值进行比较。 如果当前元素已经大于或等于，我们可以保持它不变，因为它不违反非递减要求。 
3.如果当前元素小于之前的调整值，我们尝试使用允许的运算效果来减少之前的元素，而不是强制增加。 由于操作会同等地减少两个相邻值，因此唯一可行的调整是有效降低先前的贡献，以便当前元素不会被迫超过它。 
4. 关键的可行性条件是能否在不打破先前约束的情况下将先前的调整值降低到当前值。 如果没有，我们必须立即断定不可能。 
5. 在整个阵列中继续此过程，始终更新“有效先前值”以反映最严格的有效配置。 

### 为什么它有效

 不变量是处理后索引$i$，存储的值代表最小可达到的值$a_i$在保留前缀的任何有效操作序列下$[1..i]$非减少。 每个操作仅对称地修改相邻对，因此它不能引入相对于较早位置增加前缀元素的新能力。 因此，如果在任何一步我们无法对齐$a_i$有了这个不变量，未来的操作就无法解决违规问题，因为所有未来的操作都是严格本地的，并且不能追溯性地增加早期的约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        cur = a[0]

        ok = True
        for i in range(1, n):
            if a[i] >= cur:
                cur = a[i]
            else:
                if cur < a[i]:
                    ok = False
                    break
                cur = a[i]

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```代码维护一个变量`cur`代表最后处理位置的有效值。 当下一个元素至少是`cur`，它自然地扩展了非减序列。 当它较小时，我们尝试“拉低”先前的约束，但由于我们无法增加任何东西，因此当结构无法吸收下降时，就会发生故障。 

重要的实现细节是我们从不尝试显式模拟操作。 该操作的唯一相关效果是它允许相邻值的等量减少，这在不断演变的前缀状态上崩溃为单调可行性条件。

 ## 边缘情况

 关键的边缘情况是在较长的递增前缀之后急剧下降，例如$[1, 2, 3, 100, 1]$。 该算法在最后一步拒绝了这一点，因为维护的前缀约束变得与突然减少不兼容。 该操作无法相对于较早的元素“提升”最后一个元素，因此任何局部归约序列都无法修复倒置。 

另一个边缘情况是交替序列，例如$[4,5,4,5,4,5]$。 即使可以减少局部对，全局结构仍然会迫使重复的约束违反，并且当模式破坏单调可行性时，算法会提前正确地失败。 

最终的边缘情况是已经排序的输入。 由于不需要任何操作，因此不变量永远不会触发冲突，算法会立即接受序列。
