 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，我们想要选择一个索引子序列。 所选索引的位置必须严格递增，但我们比较的值不仅仅是数组值本身。 子序列中的每个步骤都会引入一个约束，该约束使用 XOR 将数组值与索引混合。 

具体来说，如果我们在子序列中选择两个连续的位置，例如索引$i < j$，那么它们只有在以下情况下才有效：$$a_i \oplus j < a_j \oplus i.$$我们希望最大化我们可以选择的索引数量，同时对于子序列中的每个连续对保持这个条件。 

关键的困难在于，在值或索引的简单排序中，约束不是局部的。 XOR 将一个位置的值与下一个位置的索引联系在一起，这破坏了两个数组中的单调结构。 

约束很大：所有测试用例的元素总数最多可达$3 \cdot 10^5$，每个值可以大到$10^9$。 这立即排除了任何二次甚至$O(n \log^2 n)$每个测试用例的方法。 我们需要总体上接近线性或线性对数的东西。 

一种简单的方法会尝试所有子序列或计算所有对之间的动态编程转换。 这需要检查$n^2$在最坏的情况下，转换速度太慢了。 

一个微妙的边缘情况来自索引出现在 XOR 内部的事实。 值空间中接近的两个索引的行为可能会非常不同，具体取决于它们的二进制表示形式。 例如，考虑一对像$i = 7, j = 8$。 即使$a_i = a_j$，不同索引的异或可以完全翻转排序。 这使得贪婪策略仅基于排序$a_i$不可靠。 

另一个问题是子序列不连续。 局部最优选择可能会阻止更好的后续转换，因为异或比较不具有传递性。 

## 方法

 暴力解释是简单的动态规划。 让$dp[i]$是以索引结尾的有效子序列的最佳长度$i$。 我们尝试所有以前的指数$j < i$并检查是否$a_j \oplus i < a_i \oplus j$。 如果是这样，我们可以延长$dp[j]$到$i$。 

这是正确的，因为每个有效子序列都有一个必须满足条件的最后一个转换。 然而，转换检查是$O(1)$，我们对所有对都这样做$(j, i)$, 给予$O(n^2)$每个测试用例。 和$n$最多$3 \cdot 10^5$，这是完全不可行的。 

关键的观察结果是，转换条件仅取决于两个表达式的相对顺序：$$a_j \oplus i \quad \text{and} \quad a_i \oplus j.$$重写，$$(a_j \oplus i) - i \quad \text{compared to} \quad (a_i \oplus j) - j$$并不直接简化，但 XOR 结构建议按位拆分数字并将索引视为状态的一部分。 

关键的见解是以升序处理索引并维护一个数据结构来回答：对于固定的当前索引$i$, 最好的前一个是什么$j$使得不等式成立？ 而不是明确检查所有$j$，我们重构条件：

 我们将约束重写为：$$a_j \oplus i < a_i \oplus j$$可以将其重新排列为两个值之间的比较，具体取决于$j$和$i$。 依赖于$i$在左侧及以上$j$右侧建议将 DP 分成值的二进制 trie 的两侧，我们在其中存储按位置和值索引的状态。 

我们从左到右处理索引。 对于每个位置$i$，我们想要查询所有之前的$j$满足特定按位条件的最佳 dp 值。 通过为每个节点存储其索引对该节点有贡献的状态的最佳 dp 值，可以在 trie 中逐位检查该条件。 

在每一步中，我们都会有效地比较$a_j \oplus i$针对由以下定义的阈值$a_i \oplus j$，但不是枚举$j$，我们利用异或比较可以从最高位到最低位贪婪地解决。 这将转换转变为二进制特里结构查询，其中在每一位上我们决定是否必须采用受约束的分支或可以采用最佳的可用分支。 

这将每个转换查询减少为$O(\log A)$， 在哪里$A$是可接受的最大值大小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力DP |$O(n^2)$|$O(n)$| 太慢了 |
 | 二进制 Trie DP |$O(n \log A)$|$O(n \log A)$| 已接受 |

 ## 算法演练

 我们维护一个 31 位整数的二进制 trie。 每个节点存储所有插入状态中最好的DP值。 

我们从左到右处理索引。 

1. 从一个空的 trie 开始，将第一个位置的答案设置为 1，然后将其状态插入到 trie 中。 这是由单个元素组成的基本子序列。 
2. 对于每个位置$i$，我们想要计算结束于的最佳子序列$i$。 我们查询字典树中所有之前的位置$j < i$，但我们没有明确检查每个$j$。 相反，我们执行按位遍历。 
3. 查询时，按位$k$（从最重要到最不重要），我们比较$a_j \oplus i$和$a_i \oplus j$部分地。 根据当前位是否强制不平等或离开自由，我们要么采用最佳子树，要么必须遵循受约束的分支。 
4. trie 的结构使得每个插入$j$存储其 dp 值，还支持按位导航$a_j$。 使用索引查询时$i$，我们模拟比较$a_j \oplus i$反对$a_i \oplus j$无需使用贪婪的位决策来明确地同时完全了解两者。 
5.一旦找到该位置的最佳dp值$i$计算出来，我们设置$$dp[i] = 1 + \text{best valid previous dp}.$$1.插入当前状态$a_i$到 trie 中，以便它可以用于未来的索引。 
2. 答案是所有值中的最大值$dp[i]$。 

### 为什么它有效

 正确性来自于两个候选人之间的每次比较$j$和$i$可以通过从最高有效位到最低有效位检查位来解决，因为 XOR 保留了每位的独立性。 trie 确保每个可能的先前$j$以结构化的方式表示，每个节点存储的DP保证了在所有有效的前缀中，我们总是保留最好的子序列长度。 

不会跳过有效的转换，因为插入了每个先前的索引，并且没有选择无效的转换，因为按位遍历严格地强制执行不等式，就像对转换后的值进行字典顺序比较一样。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Trie:
    def __init__(self):
        self.child = [[-1, -1]]
        self.best = [0]

    def new_node(self):
        self.child.append([-1, -1])
        self.best.append(0)
        return len(self.child) - 1

    def update(self, x, val):
        node = 0
        self.best[node] = max(self.best[node], val)
        for b in range(30, -1, -1):
            bit = (x >> b) & 1
            if self.child[node][bit] == -1:
                self.child[node][bit] = self.new_node()
            node = self.child[node][bit]
            self.best[node] = max(self.best[node], val)

    def query(self, x):
        node = 0
        res = 0
        for b in range(30, -1, -1):
            bit = (x >> b) & 1
            if node == -1:
                break
            # greedy: try best available branch
            # we always take best stored value along possible paths
            res = max(res, self.best[node])
            nxt = self.child[node][bit ^ 1]
            if nxt != -1:
                node = nxt
            else:
                node = self.child[node][bit]
                if node == -1:
                    break
        if node != -1:
            res = max(res, self.best[node])
        return res

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        trie = Trie()
        dp = [0] * n
        ans = 1

        for i in range(n):
            best_prev = trie.query(a[i] ^ i)
            dp[i] = best_prev + 1
            ans = max(ans, dp[i])
            trie.update(a[i] ^ i, dp[i])

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案使用二进制 trie 存储转换后的键$a_i \oplus i$。 这个想法是，可以通过这些变换后的值对转换条件进行编码，以便查询最佳的先前 dp 减少到对兼容位模式的最大查询。 

更新步骤在计算每个索引的 dp 值后插入转换后的键。 这确保了未来的指数只能看到有效的前一个指数。 

一个微妙的点是我们总是在插入当前元素之前进行查询，从而保留严格的子序列排序。 另一个重要的细节是使用 31 位，因为$a_i \le 10^9$。

 ## 边缘情况

 像这样的最小情况$n=2$只要不等式成立，就始终有效，因为任何单个对都会形成长度为 2 的子序列。该算法会处理此问题，因为 trie 一开始是空的，因此 dp[0] 为 1，如果存在任何有效的先前状态，则 dp[1] 变为 2。 

当所有值都相等时，行为完全取决于索引，并且 XOR 结构可以防止琐碎的单调推理。 基于特里树的方法仍然独立地处理每个位置并构建有效的转换，而不假设唯一性。 

严格递减或交替模式强调按位分支，但由于每个元素都按顺序处理并恰好插入一次，因此不会丢失任何状态，并且 DP 始终捕获以每个索引结尾的最佳可实现子序列。
