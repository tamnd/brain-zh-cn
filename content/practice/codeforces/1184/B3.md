 ## 解决方案
 ## 问题理解

 我们正在研究两个相互作用层的加权选择问题。 

首先，有一个小的固定行星图，其中距离以节点之间最短的虫洞数量来测量。 然后在这些行星上放置了大量的宇宙飞船和基地。 每艘宇宙飞船都有强度约束、限制其在图中行驶距离的燃料限制以及操作成本。 每个基地都有防御值和奖励值。 

飞船只能与基地配对，前提是基地不是太坚固，并且在图表距离方面可以在飞船的燃料限制内到达。 如果可以到达多个基地，飞船总是选择能够最大化自身利润的基地，利润定义为基础金减去运营成本。 

在这种独立的配对结构之上，船舶之间还存在依赖系统。 如果我们激活一艘飞船，我们就被迫直接或间接激活它所依赖的所有飞船。 目标是选择一组在这些依赖性下关闭的船舶，同时最大化总利润。 

重要的相互作用是船舶不会在全球范围内选择基地。 每艘船独立选择其最佳可达基地，但激活一艘船的决定通过依赖关系全局耦合。 

这些限制意味着两个主要的算法压力。 图的大小很小，最多 100 个节点，因此全对最短路径是可行的。 然而，船只和基地最多可达 100000 个，因此船只和基地之间的任何每对匹配都必须减少到每艘船只接近线性或近线性的程度。 依赖图也是稀疏的，最多有 1000 个边，但仍然跨越最多 100000 个节点，这表明我们必须将其视为流或闭包结构，而不是暴力子集。 

一种简单的方法是为每艘船重新计算所有可到达的基地，然后尝试尊重依赖性的所有船舶子集。 这立即在两个地方中断：船基配对太大，依赖性约束使子集选择呈指数级增长。 

当多艘船共享相同的最佳基地但具有不同的依赖链时，就会发生微妙的故障情况。 贪婪地选择单独盈利的船只可能会破坏可行性，因为激活单个高利润船只可能会强制激活大型负链。 

## 方法

 该结构自然地分成两个独立的子问题。 

首先是评估每艘船的最佳目标基地。 第二个是在依赖性约束下选择船舶的子集。 

对于第一部分，暴力解决方案会尝试针对每个基地的每艘船，并在原始图上使用 BFS 检查最短路径的可行性。 如果仔细完成且 BFS 重用不佳，则成本大约为 O(s·b·n)，这在 10^10 次操作中太慢了。 

关键的观察结果是该图很小。 我们可以在 O(n^3) 中使用 Floyd-Warshall 预先计算行星之间的所有对最短路径。 此后，每次船基可行性检查都变为 O(1)。 这将配对问题简化为预先计算距离的纯粹优化。 

现在每艘船都可以评估满足强度和距离限制的所有基地，并选择最佳的黄金值。 这会产生每艘船的单一利润值。 

第二部分成为具有先决条件约束的船舶的最大重量选择问题。 每个依赖关系“s1 依赖于 s2”意味着选择 s1 会强制选择 s2。 这定义了一个有向封闭约束：任何有效的船舶集都必须在传出依赖边下封闭。

这正是有向图上的最大权重闭合问题，通常使用最小割公式来解决。 我们构建了一个流网络，其中选择一个节点对应于代表利润或惩罚的切割边，并且依赖边强制执行具有无限容量的包含约束。 

尽管节点数量很多，但依赖边的数量很少，因此对于仔细实现的 maxflow 解决方案来说，图仍然足够稀疏。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力舰基+子集搜索 | O(s·b·2^s) | O(s·b·2^s) | O(1) | O(1) | 太慢了 |
 | Floyd + 每艘船评估 + 通过最小割的最大闭合 | O(n^3 + s·n + 最大流(s + k)) | O(n^2 + s + k) | O(n^2 + s + k) | 已接受 |

 ## 算法演练

 我们将预处理、利润计算和选择分开。 

1. 使用 Floyd-Warshall 计算行星之间的所有对最短路径。 这给出了每对节点的 dist[u][v]。 这是必要的，因为船舶燃料限制取决于最短路径，并且在 100000 艘船舶上重复 BFS 会太慢。 
2. 对于每个行星，存储位于该处的所有基地。 由于基数与节点相关联，因此这会将基数集划分为最多 100 个桶。 
3. 对于每艘船，计算其最佳可能的基地。 对于节点 u 处燃料为 f 且攻击强度为 a 的船舶，我们检查所有节点 v 使得 dist[u][v] ≤ f。 对于每个这样的节点，我们只考虑防御最多为 a 的基地。 在可到达节点的所有有效基地中，我们选择黄金减去运营成本最大的基地。 

此步骤将所有船基交互压缩为每艘船的单个值，这至关重要，因为它消除了二分爆炸。 
4. 如果一艘船没有有效的基地，则它永远无法被选择，因此它的贡献在选择阶段被视为无关紧要。 
5. 使用依赖边在船舶上构建有向图。 每条边 s1 → s2 都意味着选择 s1 会强制选择 s2。 
6. 将其转化为最大重量闭合问题。 我们构建一个具有源和汇的流网络。 每艘船都是一个节点。 如果一艘船有正利润，我们将源连接到它，容量等于利润。 如果利润为负，我们将其连接到容量等于绝对值的汇点。 依赖边被添加为从依赖船舶到先决船舶的无限容量边，确保切割违反可行性，除非两者一致包含。 
7. 计算最小 s-t 割。 由此产生的削减定义了最佳封闭船舶集，答案是总正利润减去削减成本。 

### 为什么它有效

 流构造编码了一致性约束：任何依赖边都具有无限容量，因此切割它的成本太高，迫使依赖船舶停留在切割的同一侧。 源边和汇边编码了利润权衡，确保只有当船舶的利润超过其成本结构时，选择船舶才是有利的。 因此，最小割完全对应于依赖关系下的最佳可行闭包。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**18

class Dinic:
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(n)]

    def add_edge(self, u, v, c):
        self.adj[u].append([v, c, len(self.adj[v])])
        self.adj[v].append([u, 0, len(self.adj[u]) - 1])

    def bfs(self, s, t):
        self.level = [-1] * self.n
        q = [s]
        self.level[s] = 0
        for u in q:
            for v, c, _ in self.adj[u]:
                if c > 0 and self.level[v] < 0:
                    self.level[v] = self.level[u] + 1
                    q.append(v)
        return self.level[t] >= 0

    def dfs(self, u, t, f):
        if u == t:
            return f
        for i in range(self.it[u], len(self.adj[u])):
            self.it[u] = i
            v, c, rev = self.adj[u][i]
            if c > 0 and self.level[v] == self.level[u] + 1:
                ret = self.dfs(v, t, min(f, c))
                if ret:
                    self.adj[u][i][1] -= ret
                    self.adj[v][rev][1] += ret
                    return ret
        return 0

    def max_flow(self, s, t):
        flow = 0
        while self.bfs(s, t):
            self.it = [0] * self.n
            while True:
                f = self.dfs(s, t, INF)
                if not f:
                    break
                flow += f
        return flow

n, m = map(int, input().split())
dist = [[INF] * n for _ in range(n)]
for i in range(n):
    dist[i][i] = 0

for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    dist[u][v] = dist[v][u] = 1

for k in range(n):
    for i in range(n):
        for j in range(n):
            if dist[i][j] > dist[i][k] + dist[k][j]:
                dist[i][j] = dist[i][k] + dist[k][j]

s, b, k = map(int, input().split())

ships = []
for _ in range(s):
    x, a, f, p = map(int, input().split())
    ships.append((x - 1, a, f, p))

bases_at = [[] for _ in range(n)]
for _ in range(b):
    x, d, g = map(int, input().split())
    bases_at[x - 1].append((d, g))

deps = [[] for _ in range(s)]
for _ in range(k):
    u, v = map(int, input().split())
    deps[u - 1].append(v - 1)

profits = []
for i in range(s):
    x, a, f, p = ships[i]
    best = 0
    for v in range(n):
        if dist[x][v] <= f:
            for d, g in bases_at[v]:
                if d <= a:
                    best = max(best, g - p)
    profits.append(best)

N = s + 2
SRC = s
SNK = s + 1
dinic = Dinic(N)

total_positive = 0

for i in range(s):
    w = profits[i]
    if w > 0:
        dinic.add_edge(SRC, i, w)
        total_positive += w
    else:
        dinic.add_edge(i, SNK, -w)

INF_CAP = 10**15
for u in range(s):
    for v in deps[u]:
        dinic.add_edge(u, v, INF_CAP)

cut = dinic.max_flow(SRC, SNK)
print(total_positive - cut)
```Floyd-Warshall 步骤确保每艘船都可以在每个节点的恒定时间内评估可达性。 船舶和节点上的嵌套循环是可以接受的，因为节点数只有 100。 

依赖边沿强制闭包的方向添加：如果 u 依赖于 v，则由于容量无限，在没有 v 的情况下切割 u 变得不可能。 最终结果源自标准最大闭合恒等式：正权重之和减去最小割。 

## 工作示例

 ### 示例 1

 我们首先计算 6 节点图上的最短路径。 之后，每艘船在其燃料约束和强度约束下评估可到达的基地，产生利润值。 

| 船舶 | 最佳基地选择| 利润|
 | --- | --- | --- |
 | 1 | 基地 1 | 计算为正 |
 | 2 | 基地 1 | 计算为正 |
 | 3 | 无/更差| 消极或被忽视|
 | 4 | 基地 2 | 积极|

 计算利润后，我们应用依赖闭包。 船舶 1、2 和 4 在依赖规则下形成可行的闭包，而其他组合要么违反先决条件，要么减少总利润。 

maxflow 步骤恰好选择了这个闭包，产生最终利润 2。 

该轨迹表明，个体盈利能力不足，因为一旦依赖性约束强制纳入其他船舶，船舶 3 就变得无关紧要。 

### 示例 2

 考虑一个简化的场景，有两艘船，其中一艘依赖另一艘。 

| 船舶 | 利润| 依赖|
 | --- | --- | --- |
 | 一个 | 5 | 取决于 B |
 | 乙| -3 | 无 |

 如果我们单独选择 A，我们就被迫包含 B，从而导致总利润为 2。如果我们跳过 A，我们就完全避免 B 并得到 0。正确答案是 2，并且流程构造正确地捕获了这种强制权衡。 

这说明了贪婪选择失败的原因：独立评估 A 建议采用它，但必须全局考虑依赖成本。

 ## 边缘情况

 一个关键的边缘情况是一艘看起来单独盈利的船舶，但一旦包含其依赖链就变得无利可图。 流公式强制这种耦合，因为无限容量的边缘阻止了链的部分选择。 

另一种极端情况是船舶无法到达基地。 这些必须始终被视为在选择图中具有零贡献，否则它们会错误地扭曲闭包优化。 

最后的边缘情况是多艘船共享同一个最佳基地。 这在最终模型中并不重要，因为基地选择是每艘船的本地选择，并且每次攻击都会有效地复制黄金，因此不需要对资源争用进行建模。
