 ## 解决方案
 ## 问题理解

 我们得到一个带有加权边的无向连通图，其中每条边代表两个位置之间的走廊并具有关联的能量值。 对于每个走廊，我们需要计算一个值，该值取决于该走廊在不同边权重阈值下如何与生成树结构交互。 

解释该任务的一个有用方法是：想象我们逐渐“收紧”对允许的走廊能量的限制。 当我们降低门槛时，一些走廊就变得无法使用。 对于每个原始边，我们希望找到可能的最高阈值，这样，如果我们将该边的能量稍微修改为该阈值，该边仍然可以出现在由图的其余部分引起的某些有效的最小跨越结构中。 

因此，对于每条边，我们实际上都在问：在与图中的所有替代路径竞争时，我们可以在多大程度上减少其权重，同时仍然使其有资格成为至少一个最小生成树配置的一部分。 

制约因素很大。 对于最多 10^5 个节点和最多 10^6 个边，任何检查路径或重新计算每个边的生成树的解决方案都会立即变得太慢。 即使单个 MST 构造也是 O(m log n)，但对每条边执行此操作将远远超出限制。 这迫使我们采用全局预处理的观点，其中每个边缘答案都是从所有 MST 的结构化表示的一次或几次遍历中得出的。 

一个关键的微妙之处是最小生成树可能不是唯一的，并且具有相同权重的多个边可能会产生联系。 朴素的 Kruskal 运行给出一个 MST，但答案取决于_所有可能的 MST 替代方案_，而不仅仅是一棵选择的树。 

一种常见的失败情况是假设只有 MST 树的边很重要。 例如，如果我们选择一个 MST 并且只考虑树结构，我们就会错过不在该特定 MST 中但可能出现在另一个 MST 中且平局决胜局略有不同的边。 另一个失败是忽略仍然参与循环的较重边缘，因为循环结构决定了替换的可能性。 

## 方法

 一个蛮力的想法是独立处理每条边。 对于固定边，我们可以想象将其权重设置为某个值并重新计算最小生成树，检查是否包含该边。 为了找到最大有效值，我们每次都会对权重进行二分搜索并重新计算 MST。 

每个 MST 计算成本为 O(m log n)，并且通过对超过 30 个值的二分搜索对每条边执行此操作，大约会得到 O(m log n log C)。 当 m 达到 10^6 时，这已经成为临界点，并且在实践中，由于常数因素和重复的排序或堆操作，它太慢了。 

结构上的见解是，MST 行为完全由生成树内路径上的循环和最大边控制。 如果我们固定任何生成树，那么对于任何非树边，其进入 MST 的能力取决于其在树中端点之间的唯一路径上的最大边权重。 这减少了从全局重新计算到路径最大查询的问题。 

然而，由于没有 MST 是唯一的，我们需要一个结构来捕获_所有 MST 等效选择_。 这就产生了构建 Kruskal 流程但以保留“连接路径上的最大边缘”信息的方式合并组件的想法。 正确的工具是增强为合并树的并查找结构，通常称为 Kruskal 重建树。 它对组件如何随着边权重的增加而合并进行编码，并且该树中的路径查询对应于任何 MST 一致结构中的最大边。 

一旦构建了这棵树，每个原始边都可以映射到合并树中的最低公共祖先问题，并且答案减少为路径上的单个最大权重查询。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（重新计算每条边的 MST）| O(m² log n) | O(m² log n) | O(n + m) | 太慢了 |
 | Kruskal + 重建树 + LCA 查询 | O(m log m + m log n) | O(m log m + m log n) | O(n + m) | 已接受 |

 ## 算法演练

 我们构造了一个 Kruskal 风格的合并过程，但我们没有丢弃结构，而是显式地构建了组件合并的二叉树。 

1. 按权重以非降序对所有边进行排序。 这与 Kruskal 考虑它们的顺序相匹配，确保我们以递增的阈值顺序处理 MST 约束。 
2. 初始化 DSU，其中每个节点都是其自己的组件。 我们还在一个单独的“合并树”中创建新节点来表示联合操作。 
3. 按排序顺序处理边。 对于连接分量 a 和 b 且权重为 w 的边，我们找到它们的 DSU 根。 如果它们不同，我们创建一个表示这两个组件的并集的新节点，为其分配权重 w，并将两个组件根附加为该节点的子节点。 然后我们在 DSU 中将它们联合到这个新节点。 

这一步至关重要，因为每个合并节点代表了克鲁斯卡尔过程中两个组件连接的确切时刻，并且该合并的权重是连接它们的最小边。 
4. 所有并集后，我们得到一棵最多有 2n 个节点的树。 原始节点是叶子，内部节点表示沿着任何根路径权重不断增加的合并。 
5. 我们为 LCA 查询预处理此合并树，为每个节点存储其父节点和深度。 
6. 对于每个原始边 (u, v, w)，我们计算合并树中 u 和 v 的 LCA。 与该 LCA 节点关联的值表示 u 和 v 在 Kruskal 过程中连接的最小阈值。 边缘所需的答案就是这个 LCA 权重。 

直觉是，合并树对所有 MST 一致结构中任意两个顶点之间的精确连接阈值进行编码。 

### 为什么它有效

 在每次合并时，我们都会模拟使用边达到给定权重来连接两个组件的最早可能点。 两个原始顶点之间的任何路径都必须经过该合并树中它们的最低公共祖先，并且该祖先的权重是允许它们之间连接的最小阈值。 该值表征了 MST 循环中控制替换行为的最强瓶颈边，这正是决定边是否可以在某些 MST 中被替换的因素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
edges = []
for i in range(m):
    a, b, w = map(int, input().split())
    edges.append((w, a - 1, b - 1, i))

edges.sort()

parent = list(range(2 * n))
value = [0] * (2 * n)
children = [[] for _ in range(2 * n)]

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

next_id = n

for w, a, b, _ in edges:
    ra, rb = find(a), find(b)
    if ra != rb:
        cur = next_id
        next_id += 1
        value[cur] = w
        parent[ra] = cur
        parent[rb] = cur
        children[cur].append(ra)
        children[cur].append(rb)

for i in range(2 * n):
    find(i)

LOG = 20
up = [[-1] * (2 * n) for _ in range(LOG)]
depth = [0] * (2 * n)

root = next_id - 1 if next_id > n else 0

stack = [root]
order = []
while stack:
    v = stack.pop()
    order.append(v)
    for c in children[v]:
        depth[c] = depth[v] + 1
        up[0][c] = v
        stack.append(c)

for k in range(1, LOG):
    for v in range(2 * n):
        if up[k - 1][v] != -1:
            up[k][v] = up[k - 1][up[k - 1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    k = 0
    while diff:
        if diff & 1:
            a = up[k][a]
        diff >>= 1
        k += 1
    if a == b:
        return a
    for k in reversed(range(LOG)):
        if up[k][a] != up[k][b]:
            a = up[k][a]
            b = up[k][b]
    return up[0][a]

ans = [0] * m
for w, a, b, i in edges:
    l = lca(a, b)
    ans[i] = value[l]

sys.stdout.write("\n".join(map(str, ans)))
```第一部分构建 Kruskal 合并树，其中每个并集创建一个新的内部节点，标记有负责合并的边权重。 这`value`数组存储此阈值信息。 

DFS 式遍历为 LCA 查询准备二进制提升表。 每个节点都以两倍距离的幂存储其祖先，从而允许快速跳跃。 

对于每条边，我们在合并树中查询其端点的 LCA。 该 LCA 对应于连接这些顶点的最早合并点，其存储的值是该边的正确最大可行阈值。 

一个微妙的点是，我们将合并结构视为有根树，即使 DSU 合并在概念上是无向的。 构造的父指针强制执行有效的层次结构，因为每个新节点的权重顺序严格更高。

 ### 示例 1

 输入：```
3 3
1 2 8
2 3 3
3 1 4
```排序的边：

 | 步骤| 边缘| DSU 合并 | 新节点权重 |
 | --- | --- | --- | --- |
 | 1 | (2,3,3) | 合并| 3 |
 | 2 | (3,1,4) | (3,1,4) | 合并| 4 |
 | 3 | (1,2,8) | 合并| 8 |

 我们构建一个合并树，其中 1 和 3 首先在 3 处连接，然后该组件在 4 处连接到 2，最后 8 形成更高的合并。 

查询结果：

 | 边缘| 生命周期评估 | 价值|
 | --- | --- | --- |
 | 1-2 | 1-2 4 节点 | 4 |
 | 2-3 | 2-3 8 节点 | 8 |
 | 3-1 | 3-1 8 节点 | 8 |

 这符合这样的直觉：端点之间的瓶颈是由连接它们的最早的合并确定的。 

### 示例 2

 输入：```
4 4
1 2 5
2 3 6
3 4 1
1 4 4
```排序：

 | 步骤| 边缘| 合并权重 |
 | --- | --- | --- |
 | 1 | 3-4 | 3-4 1 |
 | 2 | 1-4 | 1-4 4 |
 | 3 | 1-2 | 1-2 5 |
 | 4 | 2-3 | 2-3 6 |

 该结构构建了一个层次结构，其中低权重的边首先合并，较高的边连接在上面。 

对于边 1-4，其 LCA 出现在权重 4 处，因为这是它们在重建树中连接的第一个点。 

对于边 2-3，连接仅发生在顶部合并处 6 处。 

这表明即使是非树边缘也如何从结构连接中获得答案，而不是直接包含在选定的 MST 中。

 ## 边缘情况

 关键的边缘情况是多个边缘共享相同的权重。 在这种情况下，Kruskal 可能会以不同的顺序合并组件，但重建树仍然在同一级别上合并它们，因为所有等权边都按排序顺序一起处理。 该算法确保任何歧义都不会影响 LCA 结构，因为所有此类合并都发生在标有相同权重的节点下，从而保留了正确的瓶颈值。 

当图已经是一棵树时，会出现另一种边缘情况。 那么每条边都是 MST 的一部分，并且每条边都应该返回自己的权重。 在重建树中，每条边都成为直接合并节点，因此其端点的LCA正是该边创建的节点，立即产生正确的值。 

最后的边缘情况是当图很密集并且两个节点之间存在多个替代路径时。 重建树将所有这些替代方案压缩到单个合并层次结构中，确保即使存在许多循环，答案也仅取决于首先连接端点的最高瓶颈合并。
