 ## 解决方案
 ## 问题理解

 我们给出了 2D 平面上的一组点和曼哈顿距离的固定半径。 任务是在平面上的任意位置选择一个中心，不一定是在整数坐标处，并找到最多位于曼哈顿距离内的给定点的最大数量`r`从那个中心。 

从几何角度来看，曼哈顿球是一个与轴对齐的菱形区域。 对于选定的中心，我们想要计算有多少点落在该菱形内，并且我们可以以最佳方式放置中心以最大化此计数。 

输入大小高达 300,000 个点，因此任何明确尝试每对点或每个候选中心的解决方案都会立即变得太慢。 在最坏的情况下，二次方法已经意味着大约 9e10 次距离检查，这远远超出了 2 秒的限制。 这迫使我们避免明确列举中心。 

一个微妙的困难是最佳中心不限于整数坐标，这意味着我们不能简单地尝试网格点或现有顶点。 另一个问题是曼哈顿距离不像欧几里得距离那样旋转对称，因此标准圆覆盖技巧不直接适用。 

一个天真的错误是假设最好的中锋总是在其中一个点。 例如，对于形成对称十字形状的点，最佳中心可能位于它们之间，而不是正好位于任何点上，因为稍微移动可以增加覆盖范围。 

## 方法

 直接的暴力策略是选择每个点作为潜在的中心并计算有多少个点位于距离内`r`。 仅当我们假设最佳中心始终是一个点时，这才是正确的，这在曼哈顿几何中是无法保证的。 即使忽略正确性问题，这也已经花费了 O(n²)，因为对于每个中心，我们扫描所有点。 

为了同时保证正确性和效率，我们需要一个结构，在坐标变换后将曼哈顿球变成轴对齐的东西。 关键的观察结果是曼哈顿距离在 45 度旋转下变得更加简单。 如果我们定义新坐标：

 x' = x + y

 y' = x - y

 那么条件 |x - x0| + |y - y0| ≤ r 变换为：

 max(|x' - x0'|, |y' - y0'|) ≤ r

 这会将菱形转换为变换空间中的轴对齐正方形。 

于是问题就变成了：求在(x',y')空间中一个边长为2r的轴对齐正方形可以覆盖的最大点数。 

现在的任务是经典的二维正方形最大重叠。 我们可以按 x' 对点进行排序并使用滑动窗口，从而维护 y' 上的结构。 对于排序顺序中的每个候选左边界，我们包括 x' 在 2r 范围内的所有点，并在 y' 上维护一个数据结构（多重集或两个指针加上 Fenwick 树的坐标压缩），以计算有多少个点位于大小为 2r 的 y' 区间内。 

然后我们滑动窗口并动态维护计数。 

关键思想是，按 x' 排序后，问题简化为在移动 x' 窗口内重复求解 y' 上的一维范围最大计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（每个点的中心）| O(n²) | O(1) | O(1) | 太慢了 |
 | 最优（变换+滑动窗口+平衡结构）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 将每个点 (x, y) 变换为 (x + y, x - y)。 这会将曼哈顿距离转换为轴对齐的 L∞ 约束。 
2. 按 x' 对所有变换点进行排序。 
3. 在 x' 上维护一个滑动窗口，使得窗口中的所有点满足 x'[右] - x'[左] ≤ 2r。 
4. 在这个窗口内，我们想知道位于长度为 2r 的 y' 任意区间内的最大点数。 这是一个一维最大滑动区间计数问题。 
5. 在 y' 上使用两指针结构以及平衡多重集或排序容器来有效地维护计数。 
6. 当我们展开右指针时，将 y' 插入到结构中。 当我们向左移动指针时，删除 y'。 
7. 对于每个右指针位置，使用二分查找结构查询 [min_y', min_y' + 2r] 中有多少个点。 
8. 跟踪所有窗口位置的最大结果。 

### 为什么它有效

 该变换准确地保留了曼哈顿距离，即每个 L1 球在变换后的空间中都变成了 L∞ 正方形。 每个可行的中心对应于边长为 2r 的一个正方形，并且每个这样的正方形对应于原始平面中的有效曼哈顿球。 该算法通过排序和滑动探索所有最大水平放置，并且对于每个这样的放置，它通过范围计数隐式考虑所有垂直放置。 由于每个最佳方块都可以按排序顺序与某些事件边界对齐，因此滑动窗口永远不会跳过候选最佳配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from bisect import bisect_left, bisect_right

def solve():
    n, r = map(int, input().split())
    pts = []
    for _ in range(n):
        x, y = map(int, input().split())
        pts.append((x + y, x - y))
    
    pts.sort()
    
    ys = sorted(p[1] for p in pts)
    
    ans = 0
    l = 0
    active_y = []
    
    from collections import deque
    import bisect
    
    active = []
    
    for i in range(n):
        x2, y2 = pts[i]
        bisect.insort(active, y2)
        
        while pts[i][0] - pts[l][0] > 2 * r:
            active.pop(bisect.bisect_left(active, pts[l][1]))
            l += 1
        
        low = bisect.bisect_left(active, y2 - 2 * r)
        high = bisect.bisect_right(active, y2 + 2 * r)
        ans = max(ans, high - low)
    
    print(ans)

if __name__ == "__main__":
    solve()
```转换步骤直接在输入时实现，存储`(x+y, x-y)`对。 按第一个坐标排序使我们能够强制 L∞ 正方形的水平约束。 

这`active`list 在当前 x 窗口中维护 y' 值的排序多重集。 我们使用`bisect.insort`和二分搜索删除，由于列表移位，这使得在最坏情况下每次插入和删除都是 O(n)，但从概念上讲，这是预期的结构； 在生产中，我们可以将其替换为压缩坐标上的平衡 BST 或 Fenwick 树，以实现 O(log n)。 

关键的正确性细节是 y 范围查询始终锚定在当前点的 y2 处，这是有效的，因为任何最佳正方形都可以被视为其下边界与活动集中的某个点对齐。
