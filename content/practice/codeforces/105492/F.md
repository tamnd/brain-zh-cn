 ## 解决方案
 ## 问题理解

 我们得到一个建模为有向图的工厂，其中每个节点代表一个处理步骤。 每一步都以给定的概率独立失败。 除了这些内在的失败之外，还存在定向依赖关系：如果一个步骤失败，则依赖于该步骤的每个步骤也会失败，并且这种影响会通过依赖关系图传播。 

我们真正需要回答的唯一问题不是关于级联本身，而是关于选择。 在所有步骤中，我们选择失败概率最小的步骤。 输出是所选步骤不失败的概率，这意味着我们输出一减去其失败概率。 

图结构和依赖传播听起来很重要，但它们并未用于请求数量的最终计算。 它们仅定义了一个故障级联，一旦我们意识到问题从不要求传播下的节点的可达性或生存概率，该故障级联就无关紧要了。 选择纯粹基于给定的独立概率。 

约束很大：最多 100,000 个节点和 100,000 条边。 任何尝试模拟级联或计算每个节点的图闭包的解决方案都会太慢。 即使每个节点使用单个 BFS 或 DFS，在最坏的情况下也会达到 O(n(n + m))，这是不可能的。 

朴素推理的一个微妙的失败案例是过度考虑依赖关系并尝试计算传播后的“有效失败概率”。 例如，如果节点 A 依赖于 B，而 B 依赖于 A，则可能会错误地尝试计算循环的联合故障概率，即使问题从未要求这样做。 

另一个边缘情况是所有概率都相等。 答案仍然必须选择其中任何一个，并输出 1 减去该值。 如果均为 0.999，则输出为 0.001。 

最后，概率包括 0 或 1 等值。如果最小概率为 0，则答案为 1。如果为 1，则答案为 0。 

## 方法

 暴力解释首先从字面上考虑该图。 人们可能会尝试计算每个节点在级联依赖关系后最终失败的概率。 这将涉及通过具有循环的有向图对故障传播进行建模，本质上需要对强连接组件进行计算，然后沿着压缩的 DAG 传播概率。 

即使我们简化独立性假设，我们仍然需要重复遍历边来确定封闭效果。 对可到达的故障节点的任何每个节点重新计算都会导致重复的图遍历，并且在密集图中，这在实践中变成了二次方。 

然而，关键的观察是级联与输出无关。 该问题从不询问某个步骤在依赖关系中幸存下来的概率。 它只要求：在所有步骤中，选择给定失败概率最小的一个，并输出其生存概率。 

因此整个图结构可以被忽略。 我们只需要对概率进行一次线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（每个节点的图传播）| O(n(n + m)) | O(n(n + m)) | O(n + m) | 太慢了 |
 | 最佳（最小扫描）| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将问题简化为选择数组中的最小值并对其进行转换。 

1. 将所有故障概率读入数组。 我们根本不处理边缘，因为它们不影响选择标准。 
2. 维护一个变量`best`初始化为大于任何可能概率的值，例如 2.0。 这将存储迄今为止看到的最小故障概率。 
3. 迭代每个概率。 对于每个值，将其与`best`并更新`best`如果它更小。 这确保了一次通过后，`best`等于系统中的最小故障概率。 
4. 将答案计算为`1 - best`。 这表示所选步骤不会失败的概率。 
5. 输出足够精度的结果。 

忽略边缘背后的原因是，只有当我们被问及随机故障传播下所有步骤的生存或可达性时，依赖引起的故障才会重要。 在这里，选择发生在任何随机事件之前，因此依赖结构永远不会影响选择哪个节点。 

### 为什么它有效

 该问题定义了仅基于内在故障概率的确定性选择规则。 由于依赖性不会改变这些给定的概率，并且不是选择标准的一部分，因此最佳步骤正是所提供列表的全局最小值。 从失败概率到生存概率的转换是直接补充，因此从定义中可以立即得出正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    probs = list(map(float, input().split()))
    
    best = 2.0
    for p in probs:
        if p < best:
            best = p
    
    ans = 1.0 - best
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案完全忽略依赖边，因为它们与步骤的选择无关。 唯一的微妙之处是数值稳定性：我们依赖于 Python 浮点减法，考虑到所需的 1e-6 相对精度或 1e-200 绝对精度，这已经足够了。 

的初始化`best`即使所有概率都在 [0, 1] 范围内，2.0 也能确保正确性。 最后的减法直接计算生存概率。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n, m = map(int, sys.stdin.readline().split())
    probs = list(map(float, sys.stdin.readline().split()))
    
    best = 2.0
    for p in probs:
        best = min(best, p)

 ## 边缘情况

 一种边缘情况是单个节点。 用于输入`1 0`有概率`0.000`，算法集`best = 2.0`，然后将其更新为`0.0`。 输出变为`1.0`，它与定义匹配，因为唯一的步骤永远不会失败。 

另一个边缘情况是所有概率都相等。 为了`0.999 0.999 0.999`, 剩余最小值`0.999`无论顺序或边缘如何。 输出是`0.001`，与补集定义一致。 

最后的边缘情况是极端值，例如`1.000`。 算法正确地保持了`best = 1.0`，输出变为`0.0`，意味着一定的失败，这与解释是一致的。
