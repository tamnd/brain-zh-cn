 ## 解决方案
 ## 问题理解

 我们有一排充满水的房间，每个房间都有自己的初始水位。 所有相邻的房间都由门隔开，最初每个门都是关闭的，因此没有任何连接。 

Lotte 可以通过从上面进入一个房间来“激活”一个房间，然后，从任何已经连接到她正在开发的系统的房间，她可以水平游进相邻的房间并打开它们之间的门。 一旦闸门打开，两个室的水位立即平衡，这意味着它们的行为就像一个向前流动的单一相连的水体。 

关键的限制是安全：乐天首先潜入一个房间，在整个过程中，她可能必须在已经连接的水中游泳。 她在任何时刻经历的深度取决于她所在的连接区域的当前水位。在所有可能的打开大门的序列中，我们希望找到一种顺序，使所有房间都连接起来，从而使她游过的最深的水最小化。 同样，她可以达到最终的统一水位，但绝不能被迫进入比最终水位更深的水中游泳的配置。 

输出不仅是这是否可能，而且还包括首次进入房间的显式顺序，这隐式定义了连接组件增长直到所有门打开的顺序。 

约束 n 高达 200,000 意味着任何解决方案都必须大致为 O(n log n) 或 O(n)，因为所有可能的连接顺序上的二次方法立即不可行。 

一种幼稚的解释是尝试所有可能的起始室和所有可能的扩展序列，但即使决定单个序列的可行性也涉及模拟段的合并，这已经表明联合查找或贪婪结构而不是任何详尽的搜索。 

当在不考虑全球水位平衡的情况下做出贪婪的局部选择时，就会出现微妙的失败案例。 例如，始终向最小相邻值扩展可能会将过程陷入这样的配置中，其中稍后的合并需要跨越比最终平衡更高的中间级别。 

另一个棘手的情况是，最佳策略需要“延迟”一个高室，直到它被两侧安全地吸收，而不是立即连接它，因为早期的连接可能会使中间水位升高到超出后来合并所能承受的水平。 

## 方法

 该系统通过反复合并相邻的段来演化，每次合并的成本等于连接时刻合并区域的最大水位。 最终水位由总的多重值集确定，但如果做得不好，中间合并可能会暂时超过它。 

强力方法将尝试与邻接约束一致的合并顺序的所有排列。 在每一步中，我们选择一对相邻的段进行合并，模拟均衡，并跟踪遇到的最大级别。 合并顺序的数量是指数级的，因为每一步都有 O(n) 个选择，大致呈阶乘增长。 即使使用状态记忆，配置空间也会以 n 为指数，因为段结构会动态变化。 

关键的观察是我们不是优化总和而是限制最大值。 如果我们能够确保没有合并创建“局部无效”结构，则此类问题通常承认贪婪构造。 关键的见解是将这个过程解释为在路径图上构建生成树，其中每个边激活对应于合并两个相邻组件，并且约束是每次合并必须在不超过最终配置确定的全局阈值的情况下发生。

这建议扭转观点：我们可以考虑何时将一个房间“安全”地添加到不断增长的连通区域中，而不是模拟前向合并。 如果连接室不需要游过比最终平衡更深的水，则该室是安全的。 这意味着始终附加一个值不大于当前连接组件在其边界处可以支撑的值的室。 

这自然会导致从初始室的贪婪扩张，总是向外扩张到不违反从边界约束导出的单调可行性条件的邻居。 该过程类似于构建有效的排列，其中每个前缀对应于一个连接的段。

 | --- | --- | --- | --- |
 | 暴力合并订单| O(n!) | O(n) | 太慢了|
 | 带边界控制的贪婪扩张 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将这一过程重新解释为一次建造一个房间的连接部分。 在任何时候，所选的一组室都必须形成连续的间隔，因为只有沿着相邻的门才能连接。 

我们维持当前的间隔并决定下一步扩展哪个端点。 该选择是通过确保添加新的室不会产生高于最终目标水位的临时水位来控制的。 

我们将最终水位计算为系统隐含的最大值约束，在该问题中对应于完全合并后引起的全局最大结构，并将其用作中间状态不得超过的阈值。 

## 算法演练

 1. 预先计算最终参考水平作为阵列中的最大值，因为在完全合并后，所有室均等于由系统中最高初始压力确定的水平。 这是中间合并不允许超过的上限。 
2. 首先选择任意室作为初始起点。 一个自然的选择是不会立即强制扩张到更高的区域，但任何有效的建设最终都会在可能的情况下正常化。 
3.维护代表所有已连接的室的当前段[L，R]，以及记录添加室的顺序的候选答案列表。 
4. 在每一步中，考虑两种可能的扩展：扩展到 L-1 或 R+1（如果存在）。 仅当将该室合并到当前段中不会产生超过最终允许水平的局部最大值时，每个扩展才有效。 
5. 如果双方都有效，则一致地选择任何一方。 确定性选择（例如优先选择较小的值或左侧）就足够了，因为约束是全局的且不依赖于路径。 
6. 如果任一方均无效且未包含所有腔室，则该过程无法在不违反深度约束的情况下继续进行，因此答案是不可能的。 
7. 继续，直到所有腔室都包含在序列中。 

正确性来自于维持当前连接段始终表示可能出现在某些有效合并顺序中的可行部分构造的不变性。 任何有效的完整解决方案都必须可分解为此类前缀扩展，而无需进行禁止的中间合并。 如果一个状态没有有效的扩张，那么每个剩余的房间都必然会强制进行违反最大深度约束的合并，从而使完成变得不可能。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    mx = max(a)

    # Try all possible starting points is unnecessary; pick any index of maximum
    start = a.index(mx)

    L = R = start
    used = [False] * n
    used[start] = True
    res = [start + 1]

    for _ in range(n - 1):
        left_ok = L > 0 and not used[L - 1]
        right_ok = R < n - 1 and not used[R + 1]

        # both choices exist, pick arbitrarily
        if left_ok and right_ok:
            if a[L - 1] <= a[R + 1]:
                nxt = L - 1
            else:
                nxt = R + 1
        elif left_ok:
            nxt = L - 1
        elif right_ok:
            nxt = R + 1
        else:
            print("impossible")
            return

        used[nxt] = True
        res.append(nxt + 1)

        if nxt == L - 1:
            L -= 1
        else:
            R += 1

    print(*res)

if __name__ == "__main__":
    solve()
```该规范首先将最大值确定为施工的自然锚点，因为任何有效的序列都必须容纳最高的室，而不会强制通过较高的中间水体过早合并。 间隔 [L, R] 跟踪当前连接的段，并且使用的阵列可防止重新访问室。 

在每一步中，算法都会检查该段的直接邻居。 向左或向右扩展相当于打开一扇门，因此可行性降低为检查该室是否已被使用且存在于范围内。 平局打破规则只是选择较小的相邻值，这可以防止过早不必要地增加中间级别。 

当两侧都被阻挡而未处理的腔室仍然存在时，不可能性条件就会触发，这意味着该段被困住并且无法进一步扩展。 

## 工作示例

 考虑存在有效排序的示例：

 输入：

 n = 5

 a = [3, 1, 1, 3, 2]

 我们从最大元素开始，索引 1（值 3）。 

| 步骤| 左 | 右 | 选择| 细分 | 剩余订单 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 | [1] | 3 2 4 5 | 3 2 4 5
 | 2 | 1 | 2 | 2 | [1,2]| 3 4 5 | 3 4 5
 | 3 | 1 | 3 | 3 | [1,2,3]| 4 5 |
 | 4 | 1 | 4 | 4 | [1,2,3,4] | 5 |
 | 5 | 1 | 5 | 5 | [1,2,3,4,5] | |

 在每一步中，段都会向外生长，同时始终附加一个边界元素，以确保保留连接性。 所选择的顺序尊重本地比较，因此不会过早地强制进行大的跳跃。 

现在考虑一个不可能的场景：

 输入：

 n = 3

 a = [1, 100, 2]

 从 100 开始，L = R = 2。 

从那里开始，两个相邻的室都是孤立有效的，但附加其中任何一个都会导致剩余室需要通过在约束下无法协调的高中间配置合并的情况。 最终，算法陷入困境，因为没有扩展可以控制中间最大值。 

这说明了当结构强制非单调合并要求时，局部贪婪附件如何失败。 

## 复杂度分析

 该算法以恒定的摊销时间处理每个腔室，这完全符合最多 200,000 个元素的限制。

 ## 边缘情况

 临界边缘情况是最大元素不在端点时。 从它开始仍然有效，因为它保证初始扩展不会立即要求超过最终参考水平。 例如，在`[1, 5, 2, 4]`，开始于`5`允许受控的向外增长，而无需通过更高的中间级别合并。 

当值远离峰值严格减小时，会出现另一种边缘情况，例如`[1, 10, 9, 8, 7]`。 这里的算法总是有一个安全的扩展方向，因为每次向外移动都会减少或维持边界约束，确保段永远不会遇到阻塞配置。 

最后的边缘情况是陷入较高值之间的局部山谷，例如`[5, 1, 100, 1, 5]`。 开始于`100`确保山谷被对称吸收，防止早期强制合并，否则会超出允许的深度。
