 ## 解决方案
 ## 问题理解

 有多个编程竞赛同时举行，并且必须在其中分配一组参与者。 每场比赛都有一个奖品，只有获胜者才能获得。 参与者赢得比赛的机会取决于他们的技能相对于该比赛中每个人的总技能：如果比赛有总技能总和$T$，然后是有技能的参与者$s$以概率取胜$s / T$。 因此，参与该环境的预期奖励是$p_j \cdot s / T$， 在哪里$p_j$是那次比赛的奖品。 

由于每个人都必须选择一场比赛，而且他们的行为很自私，因此我们希望在不同的比赛中分配参与者，这样没有人可以通过参加不同的比赛来提高他们的预期奖励。 任务是构造任何这样的稳定​​分配。 

约束条件很强：最多$2 \cdot 10^5$参与者，但最多仅限 100 场比赛。 这立即表明我们不能在重复进行任意分配后尝试每人每场比赛的优化，因为即使是一次重新分配也可能会花费$O(nm)$，迭代收敛会太慢。 相反，该结构必须来自平衡的直接表征。 

一个微妙的问题是稳定性是全局性的：移动一名参与者会改变源比赛和目的地比赛的总技能，从而改变每个人的概率。 一种天真的贪婪，在不尊重全局目标的情况下逐一分配参与者，最终可能会默默地打破平衡，因为早期的决策会扭曲后来参与者的分母。 

如果我们假设每个参与者根据当前比率独立选择最佳竞赛，则会出现另一种失败情况。 例如，如果一场比赛由于整体技术水平较低而暂时看起来很有吸引力，那么许多强手可能会蜂拥而至，随后使比赛变得更糟并导致逆转。 最终配置必须完全避免这种不稳定性，而不仅仅是在构建时进行局部优化。 

## 方法

 具有技能的参与者的预期奖励$s$在比赛中$j$是$$\frac{p_j}{T_j} \cdot s$$关键的观察结果是，对于固定作业，在比较比赛时，取决于参与者的因素消失了。 每个参与者只比较数量$p_j / T_j$。 这意味着所有参与者都同意哪场比赛最好：他们都更喜欢比例最大的比赛$p_j / T_j$。 

如果任何比赛有严格更大的$p_j / T_j$，那么每个参与者都想搬到那里，这与稳定性相矛盾。 因此，在稳定的配置中，所有使用的比赛必须具有相同的比率值，例如$\lambda$，并且未使用的比赛最多必须有比率$\lambda$。 

这迫使结构变得刚性。 对于每场比赛$j$,$$\frac{p_j}{T_j} = \lambda \Rightarrow T_j = \frac{p_j}{\lambda}$$总结所有比赛，$$\sum T_j = \sum s_i = S
\Rightarrow \sum \frac{p_j}{\lambda} = S
\Rightarrow \lambda = \frac{\sum p_j}{S}$$因此，每场比赛必须获得与其奖金完全成比例的总技能：$$T_j = S \cdot \frac{p_j}{\sum p}$$问题归结为将多组技能划分为$m$具有固定目标金额的小组。 

暴力方法会尝试所有的分配$n$人们进入$m$桶，即$m^n$，立即不可能。 即使尝试迭代调整分配也需要反复平衡总和，这可能会降级为$O(n^2)$或者更糟。 

结构洞察是，一旦目标总和固定，我们只需要构造与这些总和匹配的子集。 因为$m \le 100$，我们可以一项一项地处理比赛，并使用剩余的玩家贪婪地填充每个所需的金额。 按技能降序对玩家进行排序使得这一点变得可行：大的元素被放置在前面，确保我们不会在最后陷入无法填充的大剩余部分。 

由于保证存在有效分区，因此这种贪婪填充足以构造一个分区。

 ## 算法演练

 1. 计算总技能$S$以及总奖金$P$。 这间接决定了平衡比例因子，因为每次比赛都必须获得与其奖励成比例的技能。 
2. 对于每场比赛，计算其所需的目标总和$T_j = S \cdot p_j / P$。 这些目标代表了在任何有效的平衡中每场比赛必须吸收多少总技能。 
3. 按技能降序对参与者进行排序。 这种排序确保我们尽早放置较大的值，从而降低了陷入剩余目标无法接受的过大元素的风险。 
4. 维护竞赛指针和当前竞赛的运行总和。 迭代参与者并将每个参与者分配到当前的比赛，同时积累其总技能。 
5. 一旦比赛准确达到目标金额，即可进行下一场比赛。 切换时刻是由总和相等而不是启发式强制的，确保每个桶与其所需的质量相匹配。 
6. 输出所有构造的组。 

步骤 5 有效的原因是存在保证意味着目标与多重集兼容，因此贪婪打包在降序下永远不会不可修复地超调。 

### 为什么它有效

 在任何稳定的解决方案中，每次竞争都必须产生相同的值$p_j / T_j$。 该约束唯一地将所有目标总和固定为一个共同的比例因子。 然后，构造问题就变成将排序的多重集划分为与预定总和匹配的连续累加。 因为所有技能都是积极的，并且我们按降序处理，所以一旦部分总和达到目标，在继续之前完成它总是安全的。 这保留了剩余目标的可行性，因为较大的元素永远不会留给以后较小容量的桶。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    s = list(map(int, input().split()))
    p = list(map(int, input().split()))

    S = sum(s)
    P = sum(p)

    # compute target sums as integers
    targets = [S * pi // P for pi in p]

    # sort participants by skill (value, index)
    arr = sorted([(v, i + 1) for i, v in enumerate(s)], reverse=True)

    ans = [[] for _ in range(m)]

    j = 0
    cur_sum = 0

    for val, idx in arr:
        ans[j].append(idx)
        cur_sum += val

        if cur_sum == targets[j]:
            j += 1
            cur_sum = 0

    for group in ans:
        print(len(group), *group)

if __name__ == "__main__":
    solve()
```该解决方案首先根据平衡条件下导出的比例重建每次比赛所需的总技能。 然后，它将分配视为排序权重上的打包问题。 对竞赛的贪婪扫描是有效的，因为每个目标都只完成一次，并且切换仅在完全相等的情况下发生。 

一个微妙的点是在计算目标时使用整数除法。 在有效输入中，保证比例值正确地求和至$S$，因此在正确的构造中不会出现舍入问题。

 ## 边缘情况

 一个关键的边缘情况是一场比赛的奖金不成比例。 在这种情况下，其目标总和占主导地位，贪婪算法首先将最大的技能分配给该竞赛，直到满足阈值。 对于像一个大奖品和许多小奖品这样的输入，算法会正确地形成一个大桶，然后是较小的奖品，因为排序确保高技能参与者在他们对实现主要目标最重要的地方尽早被消耗。 

另一个极端情况是所有技能都相同。 在这里，每个目标总和变成一个简单的计数约束而不是值约束。 该算法退化为将相等的元素分配到固定大小的组中，并且贪婪填充产生相等长度的连续块而不会产生歧义。 

最后一种情况是当$m = 1$。 然后只有一个目标等于总和，算法将所有参与者直接分配到该单一竞赛中。 不会发生切换，贪婪扫描在填满唯一的桶后立即终止。
