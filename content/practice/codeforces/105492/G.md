 ## 解决方案
 ## 问题理解

 每件商品的价格精确到小数点后两位。 您可以将一组物品分成几组，每组都可以用现金或卡支付。 卡付款按照该组中的项目的确切金额收取费用。 现金支付采用四舍五入规则：总额四舍五入到最接近的 0.05 欧元的倍数。 由于您选择每组的付款方式，并且还选择如何将项目分组，因此任务是最小化最终的总成本。 

关键的自由在于分组是任意的。 物品除了价格之外没有任何结构。 每个项目都可以单独分组，或者所有内容都可以合并，或者介于两者之间，并且每个组独立选择是四舍五入还是精确支付。 

输入大小最多为 2·10^5 项，这排除了任何显式考虑分区或子集的解决方案。 分组或子集总和中的任何指数都是不可能的。 即使是针对项目对的二次策略也太慢了。 

主要的微妙之处来自于现金舍入规则。 舍入到最接近的 0.05 意味着以 0.01-0.02 结尾的值会下降，0.03-0.04 会上升，类似地在 0.06-0.07 左右，等等。这使得分组变得非常重要，因为组合项目会以非线性方式改变舍入行为。 

一个天真的错误是假设每个项目都应该独立支付，或者将所有项目分组是最佳的。 两者都失败了。 例如，如果以现金支付，像 1.01 和 1.01 这样的两项单独四舍五入为 1.00，但合计为 2.02，四舍五入方式不同，并且根据分值的不同，表现可能更差或更好。 

另一个常见的失败是假设以分模 5 进行的贪婪配对总是有效，而无需仔细计算总和之间的进位。 舍入效果取决于一组的总美分 mod 5，而不仅仅是单个项目。 

## 方法

 我们首先将价格转换为整数美分，以消除浮动精度问题。 每个价格都变成以美分为单位的整数 p。 现金四舍五入到最接近的 5 美分意味着我们关心 p mod 5。 

如果我们考虑一个群体，只有总和模 5 才能决定现金是否有利。 对于总金额为 S 的组，现金支付为 S，四舍五入到最接近的 5 倍数。该四舍五入最多增加 2 美分或最多减去 2 美分。 

卡支付始终等于 S。 因此，对于每个组来说，如果四舍五入不会增加成本，那么现金是有利的； 否则卡更好。 重要的观察是，我们希望形成其总和具有有利余数 mod 5 的组。 

蛮力将枚举 n 个项目的所有分区，计算组总和，并评估每个组的舍入。 分区的数量是指数级的（贝尔数），这使得超过很小的 n 是不可行的。 

关键的见解是避免考虑任意分组，而是推理如何将项目配对以控制余数 mod 5。每个项目在 {0,1,2,3,4} 中贡献一个余数。 分组相当于将这些残基组合起来。 成本影响仅来自于有多少组以每个残留模式结束。 

这将问题简化为残基的计数和配对问题。 我们贪婪地将互补残基配对以最小化舍入损失：1 对与 4，2 对与 3，而 0 个项目是中性的。 任何剩余的物品都会形成一个组，我们根据四舍五入的效果选择更便宜的现金或信用卡。

 ## 算法演练

1. 通过乘以 100 将每个价格转换为整数美分。这可以避免浮点错误并使舍入纯粹算术。 
2. 计算每个价格模 5 的余数。这捕获了现金四舍五入的行为，因为四舍五入是 5 美分的倍数。 
3. 计算有多少项属于从 0 到 4 的每个剩余类别。这将整个输入压缩为五个频率。 
4. 将余数为 1 的项目与余数为 4 的项目配对。每个这样的对形成一个总余数为 0 mod 5 的组，这是现金舍入的最稳定情况。 
5. 出于同样的原因，将余数为 2 的项目与余数为 3 的项目配对。 这些也抵消了舍入效应。 
6. 任何剩余的未配对物品将单独处理。 对于每一项，通过将商品价值与其四舍五入到 5 美分的价值进行比较来决定用现金还是刷卡支付更便宜。 
7. 将所有组成的小组和未配对项目的贡献相加，以获得最终的最低成本。 

配对起作用的原因是只有组的总模 5 会影响舍入。 通过取消可能导致舍入效率低下的残差，我们减少了舍入带来额外成本的组的数量。 

### 为什么它有效

 现金四舍五入仅取决于组模 5 的最终总和。任何分组策略都可以视为将残差划分为子集，其总和模 5 决定成本调整。 1 与 4 配对以及 2 与 3 配对以最具成本效益的方式消除了所有非零残基，因为这些配对完全抵消了 5 的倍数。任何剩余项都无法通过进一步拆分来改进，因为它们会重新引入非零残基组，而没有任何补偿效益。 这表明最佳结构总是减少到互补残基的独立抵消。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def round5(x):
    r = x % 5
    if r <= 2:
        return x - r
    else:
        return x + (5 - r)

n = int(input())
a = list(map(lambda x: int(round(float(x) * 100)), input().split()))

cnt = [0] * 5
for x in a:
    cnt[x % 5] += 1

ans = 0

# pair 1 with 4
pairs = min(cnt[1], cnt[4])
cnt[1] -= pairs
cnt[4] -= pairs

# pair 2 with 3
pairs = min(cnt[2], cnt[3])
cnt[2] -= pairs
cnt[3] -= pairs

# all items contribute at least card cost; we adjust for cash possibility
for x in a:
    ans += x

# try improving by grouping leftovers optimally
# leftovers are handled via cash rounding savings from single items
for r in range(5):
    for _ in range(cnt[r]):

        # subtract overpay compared to card
        # (we recompute via rounding delta)

 ## 边缘情况

 单项输入揭示了算法是否在不存在组时错误地尝试形成组。 对于像这样的输入`0.05`，唯一有效的结果是该项目本身，因为不可能有分组好处。 

互补残基对（例如 0.01 和 0.04）演示了核心抵消机制。 它们的总和可以被 0.05 整除，因此任何正确的解决方案都必须确保它们被有效地视为零损失组。 

大量同质输入（例如 0.99 的多个副本）测试重复残基是否正确累积。 除非配对，否则每个项目都会独立运行，因此算法不得引入超出残差平衡的人为分组。
