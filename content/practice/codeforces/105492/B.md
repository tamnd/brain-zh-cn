 ## 解决方案
 ## 问题理解

 我们得到一个有向图，其中每个节点代表一个交叉点，每条边对应于四个基本方向之一的单向道路。 从每个交叉路口，最多可能有四条标记为北、东、南和西的外出道路，并且每条这样的道路都通向另一个交叉路口或不存在。 

汽车从交叉路口 1 出发，必须以最少的道路穿越次数到达交叉路口 n。 每次遍历都需要单位时间，因此目标纯粹是最小化步骤。 

复杂的不是图表本身，而是如何处理转弯。 当通过网络移动时，移动的合法性取决于传入方向和传出方向之间的关系。 如果你直走，你的闪光灯必须关闭。 如果您左转或右转，则必须激活相应的转向灯。 您总共最多可以激活信号灯 k 次，但一旦激活，您就可以保持它们打开并继续进行一致的转弯，而无需额外激活。 您也可以随时停用。 禁止掉头。 

因此，真正的成本不是边缘，而是你在路径上“开始”新的转弯行为的次数。 

约束足够严格，不可能进行简单的路径枚举。 由于节点数量最多为 5000 个，k 数量最多为 20，任何尝试探索所有路径或所有转弯序列的解决方案都会发生组合爆炸。 即使仅跟踪节点的状态空间也是不够的，因为方向历史和转向模式都会影响有效性。 

当直线运动与转弯交错时，会出现微妙的极端情况。 例如，如果一条路径在直线段和转弯之间交替，粗心的解决方案可能会错误地计算多个信号灯激活次数，或者无法强制要求直线段需要关闭信号灯。 另一个棘手的情况是第一步，没有传入方向，并且允许任何传出道路，没有成本或限制。 

## 方法

 一个强力的想法是枚举从节点 1 到节点 n 的所有可能路线，同时跟踪每一步的传入方向、传出方向以及信号灯被激活的次数。 这有效地探索了状态空间中的路径，其中每个选择在每个节点处分支为最多三个有效方向。 在最坏的情况下，这会导致路径长度呈指数增长，并且由于在重新访问节点之前路径可以是任意长的，因此这是完全不可行的。 

关键的观察是，尽管存在转弯限制，该问题仍然是仔细扩展的状态空间中的最短路径问题。 确定下一步移动的合法性和成本所需的唯一内存是当前节点、我们到达的方向以及我们当前是否“致力于”转向模式或直线模式。 使用的激活数量也是状态的一部分，但以 20 为界，这使得它足够小，可以显式包含。 

这将问题转化为“（节点、传入方向、当前信号灯模式、使用的激活）”形式的状态上的图最短路径。 如果我们切换转向行为，每个转换要么保持当前模式，要么强制新的激活。 由于每次道路遍历的成本为 1，因此我们可以使用 Dijkstra 或 0-1 BFS，具体取决于我们如何建模激活约束。 由于状态空间仍然是可管理的，因此这种扩展就足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 路径长度呈指数 | 指数| 太慢了 |
 | 状态空间最短路径 (Dijkstra) | O(n·4·4·k log (n·k)) | O(n·4·4·k log (n·k)) | O(n·k) | O(n·k) | 已接受 |

 ## 算法演练

我们将每个状态建模为交叉点、我们到达的方向、当前的信号灯模式以及到目前为止我们使用的激活次数的组合。 信号灯模式捕获我们当前是否致力于左转、右转或不转弯（直行模式）。 

然后我们在这个扩展状态图上运行最短路径算法。 

1. 我们用节点 1 的起始状态初始化优先级队列，没有传入方向，没有闪光模式，零激活，距离 0。缺乏方向意味着第一次移动不受约束。 
2. 从一个状态来看，我们考虑从当前交叉口出发的每条外出道路。 每条道路都有固定的基本方向。 
3. 如果这是第一次移动并且没有传入方向，我们可以遍历任何传出边缘，而无需激活成本。 结果状态根据我们行进的方向设置下一个节点的传入方向。 
4. 否则，我们通过比较传入方向和传出方向来确定转弯类型。 这会产生直行、左转或右转，并且 U 形转弯过渡将被忽略。 
5. 如果转弯类型是直行，我们总是可以继续前进。 直线运动会强制闪光灯关闭，因此下一个状态会将闪光灯模式重置为关闭，而不消耗任何激活。 
6. 如果转弯类型是左转或右转，我们检查当前的方向灯模式。 如果它已经与所需的回合类型匹配，我们将继续进行而不使用额外的激活。 
7. 如果当前模式与所需的回合类型不匹配，我们必须激活闪光灯，将激活计数器加一并将模式设置为新的回合类型。 如果超过 k，则转换无效。 
8. 每个有效的转换都会将成本 1 添加到距离，如果结果状态改善了已知距离，我们会将结果状态推入优先级队列。 
9. 我们继续，直到处理完所有可达状态。 
10. 答案是在任何方向和任何模式下到达节点 n 的所有状态之间的最小距离，只要激活不超过 k。 

### 为什么它有效

 每条有效的物理路线都对应于该扩展图中的一个状态序列，因为状态捕获了验证下一步移动所需的所有信息：位置、方向历史和当前转向承诺。 相反，状态图中的每个转换都对应于遵守闪烁规则的物理有效移动。 因为边权重是均匀的，并且 Dijkstra 以距离递增的顺序探索状态，所以当我们第一次到达某个状态时，我们已经找到了在其激活使用约束下到达该状态所需的最小道路遍历次数。 这保证了所有有效终端状态的最小值是最佳路由长度。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

# Directions: 0=N,1=E,2=S,3=W
# turn computation via modular arithmetic
def turn_type(d_in, d_out):
    diff = (d_out - d_in) % 4
    if diff == 0:
        return 0  # straight
    if diff == 1:
        return 1  # right
    if diff == 3:
        return 2  # left
    return -1  # U-turn (invalid)

def solve():
    n, k = map(int, input().split())
    g = []
    for _ in range(n):
        g.append(list(map(int, input().split())))

    INF = 10**18
    # dist[node][dir][mode][used]
    # dir: 0-3 valid, 4 = none (start)
    # mode: 0 off, 1 right, 2 left
    dist = [[[[INF] * (k + 1) for _ in range(3)] for _ in range(5)] for _ in range(n + 1)]

    pq = []
    start_dir = 4
    start_mode = 0
    dist[1][start_dir][start_mode][0] = 0
    heapq.heappush(pq, (0, 1, start_dir, start_mode, 0))

    while pq:
        d, u, din, mode, used = heapq.heappop(pq)
        if d != dist[u][din][mode][used]:
            continue

        for d_out, v in enumerate(g[u - 1]):
            if v == 0:
                continue
            v_node = v
            if din == 4:
                # first move free
                ndir = (d_out + 2) % 4
                if d < dist[v_node][d_out][0][used]:
                    dist[v_node][d_out][0][used] = d
                    heapq.heappush(pq, (d, v_node, d_out, 0, used))
                continue

            t = turn_type(din, d_out)
            if t == -1:
                continue

            ndir = (d_out + 2) % 4

            if t == 0:
                if d < dist[v_node][d_out][0][used]:
                    dist[v_node][d_out][0][used] = d
                    heapq.heappush(pq, (d, v_node, d_out, 0, used))
            else:
                # mode: 1 right, 2 left
                if mode == t:
                    if d < dist[v_node][d_out][mode][used]:
                        dist[v_node][d_out][mode][used] = d
                        heapq.heappush(pq, (d, v_node, d_out, mode, used))
                else:
                    if used + 1 <= k:
                        if d < dist[v_node][d_out][t][used + 1]:
                            dist[v_node][d_out][t][used + 1] = d
                            heapq.heappush(pq, (d, v_node, d_out, t, used + 1))

    ans = INF
    for d in range(4):
        for m in range(3):
            for used in range(k + 1):
                ans = min(ans, dist[n][d][m][used])

    print(ans if ans < INF else "impossible")

if __name__ == "__main__":
    solve()
```该实现在扩展的状态空间上构建 Dijkstra 搜索。 方向编码使用 0-3 作为基本方向，并使用额外值 4 来表示初始未定义的传入方向。 关键的设计选择是第一次移动完全绕过转弯约束，因为没有事先的方向。 

转换逻辑明确地将直线移动与转弯移动分开。 直线移动将模式重置为关闭。 转向动作要么重复使用当前模式，要么在切换模式时消耗一次激活。 激活计数器是执行全局约束 k 的状态的一部分。 

最终答案聚合了节点 n 处的所有有效最终状态，因为到达方向和最终信号灯模式并不重要。

 ## 边缘情况

 第一个重要的边缘情况是从起始节点开始的第一个移动。 由于没有传入方向，算法必须允许任何传出道路而不强制执行转弯规则。 该实现通过使用特殊的“未定义方向”状态来处理此问题，确保在开始时不会错误地对激活进行收费。 

另一个边缘情况是完全笔直的路径。 在这种情况下，该模式必须连续重置为关闭而不消耗激活。 直线运动的状态转换明确地清除模式，确保长直走廊不会错误地累积激活使用情况。 

最后的边缘情况是沿着一条路径多次在左转和右转之间切换。 由于每个开关都会消耗一次激活，因此算法必须将激活计数存储为状态的一部分。 如果没有这个，最短路径算法将错误地假设转弯类型变化是免费的，从而在 k 很小时产生无效的解决方案。
