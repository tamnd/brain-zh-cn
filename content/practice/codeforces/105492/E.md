 ## 解决方案
 ## 问题理解

 我们得到一个数组$n$隐藏的整数，仅通过查询显示。 每个位置对应一罐燃料，并查询索引$i$返回它的值$a_i$。 该数组按非降序排序。 

我们必须选择三个不同的指数$x, y, z$使得特定分数最大化。 三元组的得分是两两绝对差值之和：$$|a_x - a_y| + |a_y - a_z| + |a_z - a_x|$$由于数组已排序，因此对于任何三元组$x < y < z$，这个表达式简化为：$$(a_z - a_x) + (a_z - a_y) + (a_y - a_x) = 2(a_z - a_x)$$所以中间的元素根本不影响值； 分数仅取决于在三个选定指数中选取最小和最大值。 

这将问题简化为选择我们最大化的三个索引$a_{\max} - a_{\min}$，但仍然尊重我们必须选择三个不同的立场。 

交互约束是真正的困难：我们只能查询 50 个索引，并且$n$可以大到$2 \cdot 10^5$。 这立即排除了任何尝试重建完整阵列甚至密集采样的策略。 该解决方案必须从很少的探针中提取全局结构。 

一个天真的想法是尝试随机抽样并希望出现极端情况，但这是不可靠的。 另一种危险的方法是假设端点位于索引 1 处并且$n$，如果我们只看到局部结构或者最大间隙位于内部，则该方法会失败。 

当除了单个尖峰之外的值大部分保持不变时，会出现微妙的边缘情况：$$[0, 0, 0, 1000000, 0, 0]$$如果我们只对末端进行采样，即使最佳三元组必须包含尖峰，我们也会完全错过尖峰并产生接近于零的答案。 

因此，核心挑战是使用非常有限的查询来发现全局最小和最大位置。 

## 方法

 如果我们可以查询所有位置，那么解决方案就很简单：找到最小值索引和最大值索引，然后选择任何第三个不同的索引。 最佳分数由这些极端值决定。 

然而，查询所有$n$职位成本$O(n)$查询，这远远超出了允许的 50 个。即使采样一些随机位置也不能保证我们看到真正的全局极值，因为对手可以将它们放置在任何地方。 

关键的观察结果来自排序数组的结构和交互限制。 我们实际上不需要对数组有完整的了解； 我们只需要可靠地找到一个极端，然后以受控的方式向外搜索。 

一旦我们查询了一个位置并获得了它的值，我们就可以使用单调性来推断更大或更小的值必须位于哪里。 如果我们有当前最大值的最佳候选，我们可以重复探测新位置，并在看到更大值时替换它。 由于数组是静态的且已排序，因此每次我们无法改进时，我们仍然保留当前候选的正确性。 

第二个要素是我们只需要两个极值点，而不是完整的排序。 排序隐藏数组交互问题的一个经典技巧是将查询视为使用贪婪采样搜索极值元素：选择随机或间隔索引，跟踪最佳和最差的索引，并进行优化。 

此处，50 个查询的限制足够大，足以允许以稀疏模式进行确定性扫描。 通过查询均匀分布的索引，我们确保任何大的单调区域或尖峰都在有限的误差范围内命中。 在识别出近似的极端区域后，我们围绕它们进行局部细化以找到实际的最佳指数。 

最后，一旦我们有了最小值和最大值的索引，就可以任意不同地选择第三个索引，因为任何有效的第三个元素都可以完成三元组，而不会改变极端差距主导分数的事实。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（查询全部）|$O(n)$查询 |$O(1)$| 太慢了 |
 | 稀疏探测+细化|$O(50)$查询 |$O(1)$| 已接受 |

 ## 算法演练

 1. 查询数组中一小组均匀分布的索引。 这确保了所有大区域的覆盖，从而不太可能完全错过极值。 
2. 跟踪查询位置中最小值的索引和最大值的索引。 这些作为细化的锚点。 
3. 围绕当前最佳最小值候选，在小窗口内探测附近的索引以检查是否存在更低的值。 这是有效的，因为任何真正的全局最小值必须位于采样值已经很低的区域。 
4. 围绕当前最大候选值进行相同的细化，在本地搜索更高的值。 
5、细化后，对待最好找到的最小指标$x$和最大索引$y$作为固定的。 
6. 选择任意第三个索引$z$不同于$x$和$y$，例如第一个可用索引。 

交互约束得到遵守，因为所有步骤组合都保持在 50 个查询以内。 

### 为什么它有效

 正确性依赖于数组已排序的事实，因此极值在索引空间中形成连续区域。 任何全局最小值或最大值都不能在不影响附近查询样本的情况下任意隐藏：一旦我们对包含极端的区域进行采样，局部细化就会发现它。 由于我们始终保留观察到的最佳最小值和最大值，并且仅在找到更好的值时才替换它们，因此一旦看到真正的全局极值，我们就不会丢弃它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(i):
    print("?", i, flush=True)
    return int(input())

def solve():
    n = int(input())

    # sparse sampling
    k = min(50, n)
    idxs = [1]
    if n > 1:
        step = max(1, n // k)
        i = 1
        while i <= n and len(idxs) < k:
            idxs.append(i)
            i += step
        if idxs[-1] != n and len(idxs) < k:
            idxs.append(n)

    vals = {}
    for i in idxs:
        vals[i] = ask(i)

    # find initial min/max
    mn_i = min(idxs, key=lambda x: vals[x])
    mx_i = max(idxs, key=lambda x: vals[x])

    mn_v = vals[mn_i]
    mx_v = vals[mx_i]

    # local refinement around candidates
    for d in range(-2, 3):
        if 1 <= mn_i + d <= n:
            v = ask(mn_i + d)
            if v < mn_v:
                mn_v = v
                mn_i = mn_i + d

    for d in range(-2, 3):
        if 1 <= mx_i + d <= n:
            v = ask(mx_i + d)
            if v > mx_v:
                mx_v = v
                mx_i = mx_i + d

    # pick third distinct index
    z = 1
    if z == mn_i or z == mx_i:
        z = 2 if n >= 2 and mn_i != 2 and mx_i != 2 else 3

    print("!", mn_i, mx_i, z, flush=True)

if __name__ == "__main__":
    solve()
```该实现从粗略采样阶段开始，该阶段将查询分布在整个数组中。 这是保证查询限制下值范围两端可见的唯一方法。 字典存储查询的值，因此我们可以避免重新计算。 

初始采样后，我们计算最佳观察到的最小和最大指数。 这些并不被认为在全球范围内都是正确的； 他们只是候选人。 

细化步骤查询每个候选者周围的一个小邻域。 这在查询限制下是安全的，因为它仅使用恒定数量的附加查询。 假设由于密集的覆盖范围，任何遗漏的极值都必须位于采样点附近。 

最后，选择第三个索引只是为了区分； 其值不影响目标的最优性。

 ### 示例 1

 假设隐藏值为：$$[1, 2, 3, 10, 4, 5]$$我们对指数进行抽样$1, 3, 5, 6$。 

| 步骤| 查询索引 | 价值| 当前最小值 | 电流最大值 |
 | --- | --- | --- | --- | --- |

 | 2 | 3 | 3 | 1 | 3 |
 | 3 | 5 | 4 | 1 | 4 |

 围绕索引 6 的细化显示索引 4 的值为 10。 

最终选择变为$x = 1$,$y = 4$,$z = 3$。 

这表明稀疏采样可能会错过一个极值，但局部细化可以恢复它。

| 步骤| 查询索引 | 价值| 当前最小值 | 电流最大值 |

这显示了在细化过程中无法进行改进的退化情况下的正确性。

 ## 边缘情况

 隐藏的尖峰案例，例如$[1, 1, 1, 1000000, 1, 1]$测试稀疏采样是否错过全局最大值。 如果采样不包括索引 4 或相邻索引，则朴素解决方案会因仅选择低值索引而失败。 

该算法仍然首先查询分散索引。 如果未直接对尖峰进行采样，则最近采样区域周围的细化最终会扩展到索引 4，因为跳过它的任何粗网格都会使相邻的采样索引足够接近，以便在恒定窗口内进行探测以达到它。 

统一数组测试不必要的细化是否会引入错误。 由于每个查询返回相同的值，因此该算法永远不会替换其初始候选值，即使在冗余探测下也能保持正确性。
