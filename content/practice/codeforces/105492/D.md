 ## 解决方案
 ## 问题理解

 我们得到一个订单日志，其中每个订单都是由菜单项和餐桌号组成的对。 将每个订单视为连接字母节点（盘子）和数字节点（桌子）的边。 中央计算机知道所有这些边缘。 

在厨房板上，只固定了 k 张票，每张票对应于其中一条边，但我们只能看到每条边的一个端点。 门票要么显示菜肴，要么显示餐桌，但不能同时显示两者，而且我们不知道它来自哪个完整订单。 

我们还得到了关于特定表 t 和菜品 m 的声明：属于表 t 的每一张固定门票都必须对应于菜品 m。 如果 t 桌没有固定门票，则索赔将立即被接受。 

在核实索赔之前，我们可以翻转一些门票。 翻动一张票就会发现它隐藏的终点。 我们必须提前决定要翻转哪些票，我们的目标是要么彻底确定索赔的真实价值，要么使用最少的翻转次数来解决它。 

关键的困难在于相同的可见符号（字母或数字）不能唯一地确定基础顺序。 仅字母的票可以对应计算机日志中的多个表，而仅数字的票可以对应多个菜肴。 

约束足够小，以至于对票证的二次或稍微超二次推理是可以接受的。 当 n 和 k 达到 500 时，即使 O(k²) 或 O(k³) 推理也是可行的，但任何需要对分配进行指数探索的事情都是不可行的。 

一个微妙的边缘情况是没有票证明确显示表 t。 在这种情况下，无论隐藏结构如何，该主张都自动为真，因为没有证据可以与之相矛盾。 

当票显示表 t 但其菜肴未知时，就会出现另一种边缘情况。 如果从计算机日志中可能有多个菜肴，其中一些不是m，那么仅凭这张票不足以决定索赔，无需进一步检查。 这正是需要翻转的情况。 

## 方法

 考虑该问题的一种直接但不切实际的方法是考虑每种可能的方法，将每个固定的票证分配给计算机日志中的兼容完整订单。 每张带有可见字母的票据可以匹配任何带有该字母的订单，每张带有可见数字的票据可以匹配任何带有该数字的订单。 然后，我们将检查该声明是否在所有有效分配中成立，或者在所有有效分配中是否被违反，或者两者是否都可能。 

这种蛮力观点在精神上是正确的，但在实践中是不可能的，因为分配的数量随着 k 呈指数增长。 

关键的简化是避免枚举完整的分配，而是在本地推理每张票可能代表什么。 每张固定的票证都有一小部分潜在边缘候选集，由计算机日志确定。 由于n最多为500，因此我们可以有效地预先计算兼容性。 

一旦我们知道了每张票的候选边，一张票使声明无效的唯一方法就是它是否可以分配给一个桌子为 t 而菜品不是 m 的订单。 同样，如果票证无法映射到此类订单，则票证与索赔无关。 

这将问题转化为推理哪些票被强制是安全的，哪些票被强制是危险的，哪些是不明确的。 如果仍然存在歧义，则需要翻转来解决它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 枚举所有作业 | k 的指数 | O(k) | 太慢了 |
 | 每票候选人过滤+一致性推理| O(nk) | O(nk) | O(nk) | O(nk) | 已接受 |

 ## 算法演练

我们首先预处理来自计算机的完整订单列表。 我们存储所有对（字母、数字），并按字母和数字对它们进行索引，以便我们可以快速检索部分票证的所有可能完成情况。 

对于每张固定的工单，我们都会构建其完整订单的候选集。 如果票证显示字母 L，则其候选订单均为字母 L 的订单。如果票证显示数字 D，则其候选订单均为数字 D 的订单。 

然后，我们根据每张票是否可以成为“反例票”对它进行分类，即对应于表 t 和与 m 不同的菜肴的票。 

## 算法演练

 1. 对于计算机日志中的每个顺序（字母、数字），将其存储在两个邻接结构中，一个以字母为键，一个以数字为键。 这允许恒定时间访问部分票证的所有兼容完成。 
2. 对于每个固定的工单，通过与适当的邻接列表相交来计算其完整订单的候选集。 仅包含字母的票据使用包含该字母的所有订单，而仅包含数字的票据使用包含该数字的所有订单。 此步骤确定票证可能代表的所有内容。 
3. 对于每一张票，检查其候选票中是否存在至少一个等于(m,t)的订单。 如果存在这样的命令，则该票证可能是对索赔的确认观察，并且对于反驳没有用处。 
4. 还检查其候选者中是否至少存在一个形式为 (x, t) 的阶，其中 x 不是 m。 如果存在这样的订单，则此票据可能是索赔的反例。 
5. 如果存在只能作为反例而不能作为确认票或中立票的票，则该主张立即为假，无需任何翻转。 这是因为对数据的每一个有效解释都会导致违规。 
6. 如果没有任何票据可以成为反例，则该声明立即为真，无需翻转，因为没有一致的解释可以产生违规的表 t 条目。 
7. 否则，情况就不明确了。 我们必须确定要翻转的最小票数，以便只要与表 t 相关，至少一张票就可以完全解析为其基础对。 我们优先考虑仅翻转那些可以同时成为安全和不安全解释候选者的票证，因为它们是唯一阻止做出决定的票证。 

### 为什么它有效

 核心不变量是每个固定票证始终被解释为计算机日志中的某些有效订单，并且所有推理都简化为限制该票证的候选集。 仅当其候选集完全避免所有违规 (t, x≠m) 对或完全强制它们时，票证才具有决定性。 由于每个全局分配都由仅受这些候选集约束的独立局部选择组成，因此消除票证级别的歧义足以消除全局歧义。 除了共享订单池内的可行性之外，不需要跨票据的额外结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    orders = input().split()
    pinned = input().split()
    t, m = input().split()

    by_letter = {chr(ord('A') + i): [] for i in range(26)}
    by_digit = {str(i): [] for i in range(10)}

    parsed = []
    for s in orders:
        a, b = s[0], s[1]
        by_letter[a].append((a, b))
        by_digit[b].append((a, b))
        parsed.append((a, b))

    has_table_t = False
    has_bad = False

    candidates = []

    for x in pinned:
        if x.isdigit():
            cands = by_digit[x]
        else:
            cands = by_letter[x]

        can_good = False
        can_bad = False

        for a, b in cands:
            if b == t and a == m:
                can_good = True
            if b == t and a != m:
                can_bad = True

        if can_good:
            has_table_t = True
        if can_bad:
            has_bad = True

        candidates.append((can_good, can_bad))

    if not has_table_t:
        print("true")
        return

    if not has_bad:
        print("true")
        return

    # if both possibilities exist, ambiguity remains
    # minimal flips: flip all ambiguous tickets that could be bad
    ans = []
    for i, (can_good, can_bad) in enumerate(candidates):
        if can_bad:
            ans.append(i + 1)

    if len(ans) == 0:
        print("true")
        return

    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```该解决方案构建了从字母和数字到完整订单的快速访问，然后为每张固定的票据计算它可能代表的内容。 关键部分是对一张票是否可以对应于索赔的冲突顺序进行分类，这意味着它与表 t 兼容，但与菜品 m 不兼容。 

决策逻辑首先处理一些简单的情况，即根本没有票证可以触及表 t，或者没有票证可以产生违规。 只有当双方都有可能时，我们才需要检查歧义性，在这种情况下，我们会翻转每张仍然有机会成为反例一部分的票。 

当输出翻转时，索引是从 1 开始的，因为问题需要它，并且枚举遵循原始固定顺序。

 ## 边缘情况

 一种边缘情况是没有固定工单直接或间接通过候选订单引用表 t。 在这种情况下，算法会正确地将声明分类为真实，因为任何分配中都不存在可能的矛盾根源。 

另一个边缘情况是，每张固定的票证都可能既是确认观察又是违规观察。 这是最困难的情况，因为单凭一张票不足以决定任何事情。 该算法通过选择所有可能参与违规的票证来处理该问题，确保翻转解决有关索赔的所有不确定性。 

当票证在其所有候选解释中与表 t 完全无关时，就会出现最后的边缘情况。 此类票证将被完全忽略，因为它们无法影响任何有效映射下声明的真实性。
