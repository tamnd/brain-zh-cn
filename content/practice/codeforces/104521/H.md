 ## 解决方案
 ## 问题理解

 两个人在小行星线外开始：杰西在第一个小行星之前开始，杰瑞在最后一个小行星之后开始。 每颗小行星都有固定的大小，两个玩家一步步朝对方移动，直到最终到达同一个小行星。 

每时每刻，杰西都站在当前会议间隔左侧的某个位置，而杰瑞则站在右侧。 只有当杰西当前所在的小行星至少与杰瑞当前所在的小行星一样大时，杰西才会满意。 这个约束必须在每次移动之后都成立，而不仅仅是在最后。 

我们被要求构造一个恰好包含 n+1 步的序列。 每一步要么杰西向右移动一步，要么杰瑞向左移动一步。 所有移动后的最终状态必须将它们放在同一个小行星上。 在所有有效序列中，我们想要字典序上最大的序列，其中 B 被认为大于 A，因此我们更喜欢尽可能移动 Jerry。 

约束足够小，原则上每个测试用例的 O(n^2) 是可以接受的，但由于测试的总 n 最多为 5000，因此每个测试都需要任何接近线性或接近线性的解决方案。 这强烈建议使用 O(n) 或 O(n log n) 可行性检查的贪婪构造。 

一些边缘情况很容易被低估。 

如果所有小行星大小都相等，则每次移动始终有效，因此最佳答案就是首先所有 B，然后所有 A，因为按照字典顺序，B 始终是首选。 

如果该序列的左侧有一颗非常大的小行星，右侧有一个非常小的小行星，那么贪婪地过于激进地向左推杰瑞可能会提前破坏杰西的幸福感，即使存在延迟某些 B 移动的有效全局序列。 

最后，在某些情况下，移动在本地有效，但随后会导致死胡同。 这是主要的微妙之处：我们不能只检查当前的约束，我们还需要确保到达最终的交汇点仍然是可能的。 

## 方法

 暴力方法会将此视为状态 (L, R) 上的最短路径问题，其中 L 是 Jesse 的位置，R 是 Jerry 的位置。 从每个状态，我们尝试移动 A 或 B，强制执行约束，并搜索长度为 n+1 的有效序列。 这探索了指数级的可能性，因为在每一步我们都会分成最多两个选择。 即使进行剪枝，状态空间也会以最差的概念形式增长到 O(n^2) 状态和 O(2^n) 转换。 

关键的观察结果是该过程极其严格。 每次移动总是将 L 和 R 之间的距离缩小 1。 k次移动后，剩余距离是固定的，因此没有“等待”或稍后重新排列位置的自由。 这消除了大部分全局规划的复杂性。 

这种刚性允许贪婪的构造：在每一步，如果 B 保持系统有效并且仍然允许完成，我们尝试采用 B。 如果 B 不可能，我们就回退到 A。由于 B 按字典顺序更大，这保证了最佳可能的字符串。 

剩下的唯一困难是验证此举的可行性。 因为未来完全取决于剩余的移动次数，所以可行性降低到确保移动后我们不会违反端点约束。

 | 贪心有效性检查 | 每次测试 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们跟踪两个指针，L 代表杰西，R 代表杰瑞。 最初L = 0且R = n + 1，其中位置0和n+1是值为0的虚拟位置。每个A将L增加1，每个B将R减少1。在n+1次移动后，我们必须有L = R。 

在每一步中，我们都会决定是附加 B 还是 A。

1. 初始化 L = 0 和 R = n + 1。设置一个空答案字符串。 
2. 精确地重复 n + 1 次，因为每次移动都会将距离 R − L 减少 1，直到它们相遇。 
3. 尝试将 B 放在前面，因为按字典顺序它更大。 模拟 R 变为 R − 1 时的移动。 
4. 通过验证 Jesse 仍然不弱于 Jerry 来检查此举动是否有效，即 s[L] ≥ s[R − 1]。 
5. 如果检查通过，则提交移动、更新 R 并附加“B”。 
6. 否则，采取移动 A，更新 L，并附加“A”。 

这种贪婪顺序起作用的原因是，任何有效的最终序列都必须恰好由 n+1 步组成，从而将间隙从 n+1 缩小到 0。由于每个动作具有相同的结构权重，因此唯一的约束是保持每个步骤的有效性。 如果 B 在某个步骤中有效，则选择它不会降低未来的可行性，因为它只会局部更改 R，同时保留剩余移动足以缩小差距的不变量。 

### 为什么它有效

 状态由当前区间 [L, R] 完整描述，唯一重要的约束是端点比较 s[L] ≥ s[R]。 每次移动都会将间隔缩小一，因此剩余的移动次数恰好是 L 和 R 之间的剩余距离。除了在每一步选择 A 或 B 之外，未来的可达性没有分支，并且这两种操作都保留了间隔在剩余步骤中仍然可以折叠到单个点的属性。 这使得贪婪的选择变得安全：只要 B 现在有效，推迟它就无法解锁更好的字典顺序上更大的未来，因为 B 本身已经是最好的可能符号，并且不会比 A 更限制未来的移动。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = list(map(int, input().split()))
        
        # add dummy boundaries
        s = [0] + s + [0]
        
        L, R = 0, n + 1
        res = []
        
        for _ in range(n + 1):
            # try Jerry move first (B)
            if R - 1 >= L and s[L] >= s[R - 1]:
                R -= 1
                res.append('B')
            else:
                L += 1
                res.append('A')
        
        print("".join(res))

if __name__ == "__main__":
    solve()
```该解决方案显式维护两个端点，并且不需要跟踪中间位置。 两端的虚拟零点允许统一处理初始状态和最终状态，无需特殊情况。 

在每一步中，贪婪决策都是通过首先尝试性地检查 B 步来实现的。 只有当它违反约束 s[L] ≥ s[R − 1] 时，我们才会回退到 A。这确保了词典编排的极大性。 

该循环恰好运行 n+1 次，与所需的移动次数相匹配，并且每次迭代执行 O(1) 工作。

 ## 边缘情况

 n = 1 的最小输入揭示了实现是否正确处理单个决策，其中两个移动可能满足也可能不满足约束，具体取决于值。 该算法自然会处理它，因为 L 和 R 从 0 和 2 开始，并且两个转换都会根据 s[0] 和 s[1] 进行显式检查。 

当所有值都相同时，只要 L ≤ R，每个状态都满足 s[L] ≥ s[R]，因此贪婪总是选择 B，直到不可能为止。 该算法产生一长串 B，然后是 A，匹配字典最大值。 

当值严格从左向右增加时，杰瑞很快就会变得太强大而无法向左移动，迫使早期 A 移动。 一旦 B 违反端点约束，算法就会正确地回退到 A，从而防止无效状态，同时仍然尽可能最大化 B 的使用。
