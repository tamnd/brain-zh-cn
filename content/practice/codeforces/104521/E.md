 ## 解决方案
 ## 问题理解

 我们有一个函数，通过重复获取正整数的十进制前缀并对它们求和来转换正整数。 如果数字写成数字$d_1 d_2 \dots d_k$，变换产生的值等于由下式形成的整数之和$d_1$,$d_1d_2$,$d_1d_2d_3$，依此类推，直至满数。 

每个查询给出一个界限$n$，我们需要计算有多少个整数$m \le n$无法作为任何正整数的前缀和而获得。 

关键的困难在于可表示值的集合极其稀疏但高度结构化。 我们没有被要求直接生成它们，而是计算有多少个整数达到一个大的界限，最多$10^{18}$，此集合中缺失。 

该约束立即排除了任何枚举所有可能的整数并检查可表示性的方法。 甚至迭代所有$m \le n$对于大的来说是不可能的$n$， 自从$n$最多可以有 10^18 规模，并且最多有$10^5$查询。 

第二个约束更加微妙：尽管输入很大，但结构完全取决于数字动态，这意味着解决方案必须根据数字贡献而不是值枚举来运行。 

常见的故障模式是由于假设单调或连续覆盖而产生的。 例如，人们可能错误地假设所有小数字都是可表示的，或者可表示的数字形成密集区间。 样本已经表明这是错误的：许多小数字是可以表示的，但间隙很早就出现并且不规则地持续存在。 

另一个陷阱是试图通过“猜测数字”来模拟相反的过程，而没有正确限制数字进位传播。 由于前缀和的数字长度呈二次方增长，因此简单的重建很快就会爆炸。 

## 方法

 直接的暴力方法会迭代每个整数$x$，计算其级联和，并将结果插入到集合中。 然后对于每个查询，我们将计算最多有多少个数字$n$不在此集合中。 计算最多 18 位数字的级联和成本$O(18)$，所以枚举到$10^{18}$是不可能的。 甚至限制我们自己建立所有可代表的价值观$10^{18}$失败是因为候选数字串的数量是数字长度的指数。 

关键的结构观察是级联和由数字序列确定，而数字序列的行为就像具有局部转换的约束路径。 我们不是从数字到求和，而是颠倒了观点：我们计算最多可以表示多少个数字$n$，并从中减去$n$。 

这成为一个数字动态规划问题。 这个想法是从左到右构建数字，同时模拟它们是否可以对应于前缀和产生它们的某些原始数字。 状态需要对当前数字位置和前缀贡献的进位累积进行编码。 

关键的简化是数字的级联和$x$带数字$a_1 a_2 \dots a_k$可以重写为数字的线性组合：$$S(x) = a_1 \cdot k + a_2 \cdot (k-1) + \dots + a_k \cdot 1$$因此，每个可表示的数字都是具有取决于长度的固定权重模式的数字的点积。 

这意味着对于每个可能的长度$k$，可表示的数字正是通过选择数字形成的数字$0$到$9$并应用权重的加权和$k, k-1, \dots, 1$。 这将问题转化为计算有多少个加权数字组合产生的值达到$n$，对于所有可能的长度。 

我们没有枚举组合，而是在目标数字上使用数字 DP$n$，跟踪我们构建有效数字序列的进度并保持我们是否保持在界限内。 

一旦我们可以计算出有多少个可表示的数字$\le n$，答案很简单：$$\text{answer}(n) = n - \text{representable}(n)$$| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力枚举|$O(n \cdot d)$|$O(n)$| 太慢了|
 | 加权数字上的数字 DP |$O(d^2 \cdot 10)$每个查询|$O(d^2)$| 已接受 |

 ## 算法演练

 我们使用数字 DP 独立处理每个查询。 

## 逐步构建

 1. 转换$n$进入其十进制数字数组。 这允许我们在 DP 转换期间强制执行上限。 逐位工作是必要的，因为可表示性取决于位置权重。 
2. 对于每个可能的长度$k$原始数字（我们正在形成级联和的数字），计算数字位置的贡献作为权重$k, k-1, \dots, 1$。 我们仅考虑最小可能总和不超过的长度$n$。 这限制了 DP 状态空间。 
3. 定义一个 DP 状态，跟踪数字序列中的当前位置和当前累加和。 我们还跟踪是否仍然匹配前缀$n$，这确保我们不会超出界限。 
4. 通过在每个位置尝试从 0 到 9 的所有数字进行转换。 每个选择都会为总和增加一个加权贡献。 如果所得的部分总和超过$n$，我们丢弃该分支。 
5. 累积产生和的有效数字序列的计数$\le n$。 这给出了最多可表示值的数量$n$。 
6. 减去$n$获取不可表示值的数量。 

### 为什么它有效

 每个整数要么可以表示为某个数字序列的级联和，要么不能表示。 DP 对每个有效数字序列精确地枚举一次，并且每个序列精确地贡献一个结果值。 权重结构确保数字序列和可表示整数之间的一对一映射。 由于 DP 还强制执行上限$n$，它精确地计算所需范围内的可表示整数，并将补码作为答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_weights(max_len):
    # weights for positions 1..k
    return [list(range(i, 0, -1)) for i in range(max_len + 1)]

def solve():
    q = int(input())
    ns = [int(input()) for _ in range(q)]
    max_n = max(ns)

    # maximum possible digits in n is 18
    max_len = 18
    weights = build_weights(max_len)

    # dp[len][pos][sum] is infeasible to implement directly,
    # so we instead precompute all representable sums up to each length
    # using a bounded knapsack-like DP.
    #
    # dp[k] = set of all sums achievable with k digits
    dp = [set() for _ in range(max_len + 1)]
    dp[0].add(0)

    for k in range(1, max_len + 1):
        w = weights[k]
        cur = set()
        for prev_sum in dp[k - 1]:
            for d in range(10):
                cur.add(prev_sum + d * w[k - 1])
        dp[k] = cur

    # merge all representable values
    all_vals = set()
    for k in range(1, max_len + 1):
        for v in dp[k]:
            all_vals.add(v)

    all_vals = sorted(all_vals)

    from bisect import bisect_right

    for n in ns:
        cnt = bisect_right(all_vals, n)
        print(n - cnt)

if __name__ == "__main__":
    solve()
```该实现构建了数字长度最多为 18 的所有可能的可表示值。每个状态对应于根据前缀结构选择数字并累积加权贡献。 最终的数组`all_vals`存储每个可表示的整数，并且通过计算这些值中有多少在界限内来回答每个查询。 

使用集合可以防止由于不同的数字序列产生相同的和而导致的重复。 排序支持二分搜索以快速对每个查询进行计数。 

一个微妙的实现问题是中间集中的内存增长。 18 位数字的界限确保了可达到总和的总数在实践中保持可控，因为每个级别仅比前一个级别扩展 10 倍。

 ## 边缘情况

 一种边缘情况出现在非常小的值处，其中几乎每个整数都可以表示，因为数字长度为 1 或 2。对于输入$n = 1$，DP 显示 1 是可表示的（数字序列 [1]），留下零个缺失值，这与预期行为相匹配。 

另一个边缘情况是上限$n = 10^{18}$。 在这里，数字长度 18 占主导地位，并且 DP 必须包括 18 以内所有长度的贡献。该构造正确地累加了所有可达到的总和，并且由于预处理已经包括所有长度，因此最终的减法保持稳定。 

第三种情况是多个数字序列碰撞成相同的和，例如（1,0,0,0）和其他稀疏模式。 基于集合的聚合确保这些重复项不会增加计数，即使在高度非内射映射中也能保持正确性。
