 ## 解决方案
 ## 问题理解

 我们给定一个小整数$x$，并且我们可以添加另一个整数$y$在哪里$0 \le y \le 100$。 从这个偏移值$n = x + y$，我们计算两个数字：$n^2$和$n^3$。 然后，我们连接它们的十进制表示形式，像往常一样删除前导零，并检查生成的数字字符串是否是从 0 到 9 的数字的完美排列。 

换句话说，在形成单个字符串之后$n^2$紧随其后的是$n^3$，从 0 到 9 的每个数字在整个串联中必须恰好出现一次，不能重复或遗漏。 

输入大小很小：$x$最多为 50，并且$y$最多 100，所以$n$范围从 0 到 150。这立即排除了渐近优化的任何需要。 即使对所有候选者进行全面扫描也最多有 151 种可能性，并且每次检查都涉及计算两个整数幂并扫描它们串联的数字。 

主要的微妙之处不是性能，而是数字处理的正确性。 幼稚的方法很容易以两种方式失败。 首先，在连接之前忘记从概念上删除前导零可能会在将数字视为固定宽度字符串的实现中错误地计算数字。 例如，治疗$n^2 = 16$和$n^3 = 64$很好，但是如果有人用填充来格式化`"0016"`或者`"064"`，数字计数出错。 其次，混合整数连接逻辑而不是字符串转换可能会导致不正确的数字提取，特别是当人们试图构建一个像这样的数字时$n^2 \cdot 10^k + n^3$没有正确计算数字长度$n^3$。 

正确的解决方案必须将串联纯粹视为字符串操作并精确验证数字频率。 

## 方法

 蛮力的想法很简单。 对于每一个可能的$y$在范围内$[0, 100]$, 计算$n = x + y$，然后计算$n^2$和$n^3$。 将两者都转换为字符串，连接它们，并验证结果是否恰好包含 10 个数字，以及 0 到 9 之间的每个数字是否恰好出现一次。 

这是可行的，因为搜索空间的大小是恒定的。 最坏的情况是 101 次迭代，每次迭代最多处理少数数字（因为$150^3$小于 400 万，因此字符串最多 7 位长）。 总的工作量是微不足道的。 

关键的观察结果是，没有隐藏结构可供利用，因为约束已经破坏了域。 与直接枚举相比，任何导出数字排列的代数约束的尝试都是不必要的开销。 该问题的设计使得正确性完全取决于干净地实现数字计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(101 \cdot \log n)$|$O(1)$| 已接受 |
 | 最佳|$O(101 \cdot \log n)$|$O(1)$| 已接受 |

 ## 算法演练

 1.读取整数$x$。 这是调整前的起始值。 
2. 迭代$y$从 0 到 100（含）。 每个选择代表原始数字的候选移位。 
3. 对于每个$y$, 计算$n = x + y$。 这是用于两次求幂的基数。 
4. 计算$a = n^2$和$b = n^3$。 这两个值定义了最终的数字序列。 
5. 两者都转换$a$和$b$成字符串并将它们连接为$s = str(a) + str(b)$。 在删除任何前导零的概念后，这会直接对所需的数字序列进行建模。 
6.检查长度是否$s$正好是 10。如果不是，则立即跳过该候选，因为它不能包含数字 0 到 9 的排列。 
7. 计算每个数字出现的次数$s$。 如果从 0 到 9 的每个数字都只出现一次，则返回$y$作为答案。 
8. 如果没有值$y$有效，该问题保证在有效输入下不会发生这种情况，但为了完整性，包含了后备返回。 

### 为什么它有效

 每位候选人$y$恰好产生一个确定性数字字符串，该数字字符串源自$n^2$和$n^3$。 该算法检查整个允许域中的所有可能性，因此不能跳过任何有效的解决方案。 数字频率检查直接强制执行所需的条件：当且仅当该字符串是十个不同数字的排列时才被接受。 由于域已完全穷尽并且每次检查都是精确的，因此正确性来自于对有限集的穷举验证。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_valid(n: int) -> bool:
    a = str(n * n)
    b = str(n * n * n)
    s = a + b
    if len(s) != 10:
        return False
    cnt = [0] * 10
    for ch in s:
        cnt[ord(ch) - 48] += 1
    return all(c == 1 for c in cnt)

def main():
    x = int(input().strip())
    for y in range(0, 101):
        n = x + y
        if is_valid(n):
            print(y)
            return

if __name__ == "__main__":
    main()
```该解决方案将验证隔离到辅助函数中，该函数构造连接的数字字符串并检查其频率分布。 在进行全数字计数之前，长度检查充当快速拒绝过滤器。 

一种微妙的选择是将数字转换为字符串，而不是尝试提取算术数字。 字符串转换可确保自动删除前导零，从而满足问题陈述的要求，无需额外的逻辑。

 ## 边缘情况

 一种边缘情况是当$n^2$或者$n^3$位数少于预期，这可能会影响总串联长度。 例如，小$n$值会产生短字符串，例如`"1"`和`"8"`，并且组合后的字符串远低于 10 个字符，因此必须立即拒绝。 

另一个边缘情况是重复的数字。 例如，$n = 10$给出$n^2 = 100$，其中已经包含重复的零。 即使在检查之前$n^3$，数字频率条件失败，这说明了为什么需要计数而不是仅仅依赖长度。 

最后，由于较大的原因，有时会出现串联长度超过 10 的情况。$n$，但这种情况会通过长度检查自动过滤掉，从而确保正确性，而无需显式截断或规范化表示。
