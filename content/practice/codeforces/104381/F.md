 ## 解决方案
 ## 问题理解

 给定一个小的整数数组，我们想要计算有多少个有序的索引三元组$(x, y, z)$满足两个选定元素的乘积等于数组中的第三个元素的条件。 换句话说，我们选择数组中的任意两个位置（它们可以是相同的位置或不同的位置），将它们的值相乘，然后检查第三个位置有多少个选择与该乘积完全匹配。 

数组长度最多为100，而每个值最多为$10^4$。 这立即告诉我们，即使指数的相当简单的三次或接近三次的解决方案也是可行的，因为$n^3 = 10^6$在最坏的情况下，这在 Python 的限制范围内。 不可行的是迭代所有值对直到$10^4$并重复进行大量的每个值计算，因为这会在不利用小值的情况下引入不必要的开销$n$。 

这个问题的一个微妙问题是多重性。 如果一个值在数组中出现多次，则每次出现都会单独作为有效索引。 因此，即使出现相同的数字三元组，不同的索引组合也必须单独计数。 例如，在数组中$[1, 1, 1]$, 三重$(x, y, z)$对于每个指数选择都有效，产生$3^3 = 27$有效的三元组，而不仅仅是一个。 

另一个边缘情况是当产品超过数组中的最大值时。 这些情况仍然很重要，因为我们不是在有限范围的值上工作，而是在输入数组中实际出现的值上工作。 即使产品很大，如果它出现，它仍然可能与数组中的某些元素匹配。 

最后，请注意$x, y, z$是有序索引，所以$(x, y)$不同于$(y, x)$，即使值相同。 这种排序效应对于正确计数至关重要。 

## 方法

 最直接的方法是迭代所有可能的索引三元组$(x, y, z)$, 计算$a_x \times a_y$，并检查它是否等于$a_z$。 这是正确的，因为它直接强制执行每个可能的有序选择的条件。 这样的三元组的数量是$n^3$，在最坏的情况下是$100^3 = 1{,}000{,}000$，这在具有紧密循环的 Python 中是可以接受的。 

稍微不同的蛮力是首先修复$z$，然后尝试所有对$(x, y)$并测试他们的产品是否等于$a_z$。 这在逻辑上是相同的，但通常更容易构建，因为它将目标值与生成对分开。 

不需要更先进的技术，例如值域上的散列产品或频率图，因为域大小足够小，直接枚举已经可以轻松通过。 任何使用字典预先计算所有配对产品的尝试仍然会花费$O(n^2)$，然后我们乘以另一个$O(n)$匹配因子，导致相同的复杂性类别而不改进常数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（三循环）|$O(n^3)$|$O(1)$| 已接受 |
 | 配对乘积枚举 + 匹配 |$O(n^3)$|$O(1)$| 已接受 |

 因此，最佳解决方案就是仔细排序的强力方法。 

## 算法演练

 1. 读取数组并将其存储到列表中。 我们需要通过索引直接访问值，因为问题基本上是基于索引的。 
2. 将计数器初始化为零。 这将累积有效有序三元组的数量。 
3.修复索引$z$，表示乘积结果在数组中的位置。 我们将每个元素视为潜在的目标值。 
4. 对于每个$z$，迭代所有索引对$(x, y)$。 计算$a_x \times a_y$并将其与$a_z$。 每次匹配时，计数器就会递增。 
5. 所有迭代完成后，输出最终的计数器值。 

该结构确保针对每个可能的目标测试每个有序输入对，因此不会遗漏任何有效配置。 

### 为什么它有效

 每个有效的三元组$(x, y, z)$当算法达到固定索引时，明确遇到一次$z$并迭代所有对$(x, y)$。 由于所有索引都是独立枚举的并且顺序被保留，因此除了有序三元组的定义之外，不存在重复或遗漏。 因此，计数过程既完整又准确。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    ans = 0
    
    for z in range(n):
        az = a[z]
        for x in range(n):
            ax = a[x]
            for y in range(n):
                if ax * a[y] == az:
                    ans += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案直接遵循算法演练中描述的结构。 外循环固定目标索引$z$，而两个内部循环枚举所有有序对$(x, y)$。 比较是内联完成的，以避免存储中间产品，从而使内存开销最小化并改进常数因子。 

一个微妙的点是每次迭代都会进行乘法。 由于所有值都受以下限制$10^4$，乘积可以安全地容纳在 32 位整数范围内，因此 Python 中不会出现溢出问题。 另一个细节是，我们不会尝试任何早期修剪，因为条件逻辑的开销不会改善渐近行为，并且可能会恶化运行时常量。

 ## 边缘情况

 一种边缘情况是所有元素都等于 1。对于输入：```
3
1 1 1
```每对都乘以 1，并且每个索引都是有效目标。 该算法计算所有$3 \times 3 \times 3 = 27$三倍因为对于每个$z$， 全部$(x, y)$对有效。 嵌套循环自然会枚举所有组合，因此不需要特殊处理。 

另一种情况是当产品超过所有数组值时。 为了：```
3
2 2 3
```像 (2,2) 这样的对产生 4，它不存在于数组中，因此这些贡献会被自动忽略，因为没有$a_z = 4$存在。 相等性检查在迭代期间直接将它们过滤掉。 

第三种情况涉及重复的值，从而产生大量的多样性。 为了：```
4
1 1 2 2
```相对于基于集合的解释，每次出现 1 都会使贡献加倍。 该算法可以正确处理此问题，因为它独立处理索引，并且每个有效匹配都会增加计数器而不进行重复数据删除。
