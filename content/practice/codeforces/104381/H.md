 ## 解决方案
 ## 问题理解

 我们被要求找到迈克尔可以支付的最小整数，使其至少为给定值$N$，但对付款本身有数字限制。 该约束纯粹是关于我们选择的数字的十进制表示形式。 

迈克尔拒绝使用“2 或 7 的倍数”的数字。 从字面上解释，任何数字$d$如果它能被 2 整除或能被 7 整除，则被禁止。这会立即消除数字$0, 2, 4, 6, 7, 8$。 因此，唯一允许的数字是$1, 3, 5, 9$。 

任务是构造仅由这些允许的数字组成的最小数字，使其大于或等于$N$。 如果收银员收到的金额超过要求，就会找零，所以我们可以随意超额$N$只要构造的数量是有效数量中最小的。 

约束条件$N \le 10^9$意味着答案最多有 10 位数字左右，因此任何大致有效的方法$O(10^k)$或者甚至通过修剪使数字长度呈指数增长是可以接受的。 不可接受的是枚举从以下位置开始的所有整数$N$检查有效性，因为有效数字之间的差距可能很大，并且对抗性输入可能会迫使探索许多无效状态。 

一个微妙的边缘情况来自于高位的数字阻塞。 如果一个数字在$N$无效，我们不能简单地在本地替换而不考虑级联更改。 例如，如果我们尝试贪婪地递增并落在像 2 或 7 这样的禁止数字上，则天真的数字修复可能会失败：

 输入：```
27
```粗心的方法可能会尝试“修复”2 → 3 并保留 7，产生 37，这是有效的，但不是最小的。 正确答案是33，这个数字较小，但需要回溯和重新组合后缀数字。 

当多个连续数字无效或固定数字强制进位时，会出现另一个问题。 例如：

 输入：```
79
```每个位置的“下一个允许数字”可能会产生类似 91 或 93 的结果，但正确的处理必须确保该数字是全局最小的。 

这些情况表明本地数字校正是不够的； 我们必须对整个数字进行推理。 

## 方法

 蛮力策略很简单：从$N$，加1，测试所有数字是否都在$\{1,3,5,9\}$。 这是有效的，因为每个候选者都直接根据约束进行检查，保证了正确性。 

然而，有效数字的密度较低。 在最坏的情况下，我们可能会在找到有效数字之前扫描一长串无效数字。 自从$N$可以是$10^9$，并且数字限制删除了 10 个数字中的 5 个，在最坏情况模式下，有效数字之间的预期差距随着数字长度呈指数增长。 这可能会导致数十亿张支票，这是不可行的。 

关键的观察结果是有效性纯粹是位置上的并且独立于每个数字。 这使我们能够将问题视为数字构造问题而不是数字搜索问题。 我们希望受限数字集中的最小数字在所有大于或等于的有效数字中按字典顺序最小$N$。 

这自然会导致数字动态规划或带有数字回溯的贪婪构造。 该结构类似于构建具有下界约束的最小“允许位数”。 

我们从左到右处理数字，尝试匹配$N$。 如果数字无效或者我们无法严格遵守$N$，我们回溯到前一个位置并将其增加到下一个有效数字，然后用允许的最小数字填充后缀。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(\text{answer} - N)$|$O(1)$| 太慢了|
 | 最佳数字构建 |$O(L \cdot 4)$|$O(L)$| 已接受 |

 这里$L$是答案中的位数。 

## 算法演练

 我们首先将允许的数字集定义为$\{1, 3, 5, 9\}$，按升序排列。 

1. 转换$N$到一个数字列表中。 我们将首先尝试构建相同长度的候选，因为较长的数字总是较大并且我们想要最小化。 
2. 尝试构造多个长度相同的数$N$，保持“严格”约束，这意味着我们构建的前缀仍然等于$N$。 这确保我们永远不会低于$N$除非后来被迫放松。 
3. 对于每个位置，尝试放置不违反严格约束的最小允许数字。 如果该数字严格大于中对应的数字$N$，我们可以自由地用允许的最小数字填充剩余的位置。 
4. 如果在任何位置没有有效数字使我们在约束下保持有效，我们回溯到前一个位置，将其增加到下一个允许的数字，并重置所有后续位置。 
5. 如果一直回溯到第一个数字都失败，我们必须将数字的长度增加一，并用允许的最小数字填充所有数字。 
6. 返回构造好的数字。 

微妙的一点是，一旦我们超过$N$在任何位置，我们都获得自由：后缀不再受到限制，应该贪婪地最小化。 

### 为什么它有效

 在每个位置，我们都保留前缀是所有有效数字中最小的可能前缀的不变式，并且至少仍然是$N$。 每当我们偏离与$N$，我们立即切换到全局最小的后缀，因为任何更大的后缀只会增加数量而不会提高可行性。 回溯保证我们在解决方案仍然可能的最早位置探索尽可能小的数字增量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

ALLOWED = ['1', '3', '5', '9']

def solve_one(n_str):
    n = list(n_str.strip())
    L = len(n)

    def fill(k):
        return ''.join(ALLOWED[0] for _ in range(k))

    def next_allowed(ch):
        for d in ALLOWED:
            if d > ch:
                return d
        return None

    for start_len in [L, L + 1]:
        if start_len > L:
            return ALLOWED[0] * start_len

        res = [''] * start_len

        def dfs(i, tight):
            if i == start_len:
                return True

            limit = n[i] if tight else '9'

            for d in ALLOWED:
                if d < '0' or d > limit:
                    continue
                res[i] = d
                ntight = tight and (d == limit)
                if dfs(i + 1, ntight):
                    return True
            return False

        if dfs(0, True):
            return ''.join(res)

    return ALLOWED[0] * (L + 1)

def main():
    n = input().strip()
    print(solve_one(n))

if __name__ == "__main__":
    main()
```该解决方案首先尝试构建一个与以下长度相同的数字$N$，对具有严格约束的数字使用深度优先搜索。 如果失败，它会立即回退到带有一位额外数字的数字，并用允许的最小数字填充，因为任何更短或等长的解决方案都是不可能的。 

关键的实现细节是紧密标志，它跟踪当前前缀是否完全匹配$N$。 一旦“tight”变成“false”，我们就可以在任何地方自由地使用最小的数字。 

## 工作示例

 ### 示例 1：$N = 2$我们尝试构建一个 1 位数。 

| 位置 | 紧| 限制| 选择的数字| 接下来紧|
 | --- | --- | --- | --- | --- |
 | 0 | 真实| 2 | 3 | 假 |

 由于 3 是大于 2 的最小允许数字，因此我们立即超过$N$，其余的都是微不足道的。 

结果是 3。 

这显示了提前放松紧张并隐含地最小化后缀的机制。 

### 示例 2：$N = 70$我们尝试长度 2。 

| 位置 | 紧| 限制| 选择的数字| 接下来紧|
 | --- | --- | --- | --- | --- |
 | 0 | 真实| 7 | 9 | 假 |

 一旦我们在第一个位置选择 9，我们就已经超出了约束。 剩余的数字成为允许的最小数字 1。 

结果是91。 

这表明一旦我们超过$N$，我们贪婪地最小化后缀而不进行进一步比较。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(L \cdot 4)$| 每个数字最多尝试4个候选者，有深度$L$|
 | 空间|$O(L)$| 递归栈和临时结果存储|

 数字长度$L$最多为 10$N \le 10^9$，因此该算法在每次测试的恒定时间内有效运行。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    ALLOWED = ['1', '3', '5', '9']

    def solve(n_str):
        n = list(n_str.strip())
        L = len(n)

        def dfs(i, tight, res):
            if i == L:
                return ''.join(res)

            limit = n[i] if tight else '9'

            for d in ALLOWED:
                if d > limit:
                    continue
                res[i] = d
                out = dfs(i + 1, tight and d == limit, res)
                if out:
                    return out
            return None

        ans = dfs(0, True, [''] * L)
        if ans:
            return ans
        return ALLOWED[0] * (L + 1)

    return solve(inp.strip())

# provided samples
assert run("2") == "3"
assert run("70") == "91"
assert run("777777777") == "911111111"

# custom cases
assert run("1") == "1"
assert run("9") == "9"
assert run("27") == "31"
assert run("100") == "111"

 ## 边缘情况

 关键的边缘情况是输入包含全部无效的数字或强制立即回溯。 对于像 27 这样的输入，算法首先在前导数字处尝试 2，但由于不允许使用 2，因此立即失败。 然后它回溯并选择 3，并用 1 填充其余部分，生成 31。这表明该解决方案不会尝试本地修复，而是全局重新计算后缀。 

另一个边缘情况是当所有数字在允许的集合中都是最大的但仍然不足以达到时$N$，如777777777。由于7无效，算法必须跳转到更长的数字。 它产生 911111111，这是带有一位额外数字的最小有效数字。 这证实了当不存在相同长度的解时，长度扩展是必要的。
