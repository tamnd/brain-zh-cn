 ## 解决方案
 ## 问题理解

 我们有一个正方形游戏板，尺寸为$n \times n$，其中每个单元格要么是海洋，要么是一艘船。 进行单个查询：一对坐标$(r, c)$代表该板上的一个猜测的单元格。 任务是确定该确切位置上存在什么。 如果猜测的单元格包含一艘船，则对手成功击中它，答案应该是“否”。 如果细胞是海洋，则猜测失败，答案应该是“是”。 

输入格式有意最小化。 首先是棋盘的大小和猜测的坐标。 然后是完整的网格，逐行描述棋盘状态。 整个问题简化为仅检查静态矩阵中的一个单元。 

限制很小：$n \le 100$。 这立即意味着，即使是对电路板进行全面扫描，成本也微不足道，因为至多$10^4$细胞存在。 任何完全读取网格并执行恒定时间查找的解决方案都在限制范围内。 除了保持解决方案在输入大小上呈线性之外，时间复杂度问题在这里基本上无关紧要。 

此类问题的主要微妙之处在于索引一致性。 网格以行后列的形式给出，坐标从零开始。 一个常见的错误是交换行和列，或者错误地解释输入格式（例如，将网格中的空格视为单元格结构的一部分而不是分隔符）。 

一些边缘情况很重要：

 最小的情况发生在$n = 1$。 如果唯一的单元格是海洋并且查询是$(0,0)$，输出为“是”。 如果是一艘船，则输出为“No”。 天真的读者可能会错误地认为需要更大的结构，但实际上并不存在。 

另一个边缘情况是边界选择，例如查询$(0,0)$或者$(n-1,n-1)$。 这些测试索引是否正确对齐并且没有移动。 

最后一个实际的边缘情况是输入格式：在类似问题中，网格通常显示为空间分隔或连续的。 在这里，每行都包含由空格分隔的字符，因此不正确的解析（读取整个字符串而不拆分）可能会导致错误的索引或误读单元格。 

## 方法

 暴力解释仍然可以通过扫描网格中的每个单元格并检查它是否与查询的坐标匹配来解决问题。 这是有效的，因为一旦我们找到目标单元格，我们就可以直接检查它的值。 然而，即使这种方法也不必要地繁重，因为它执行$O(n^2)$无论只需要一个单元这一事实，都会进行检查。 

关键的观察是我们根本不需要搜索。 网格是明确提供的，并且感兴趣的坐标是已知的。 这将问题简化为直接数组访问：将网格读入内存并在恒定时间内索引所需的单元格。 问题的结构消除了任何遍历、搜索或预处理的需要。 

蛮力之所以有效，是因为它盲目地验证所有单元格，但当网格变大时，它就会变得低效。 通过观察查询是固定的，我们可以将网格视为静态矩阵并执行单个查找。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力扫描| O(n²) | O(n²) | 已接受但没有必要 |
 | 直接索引| O(n²) 读取输入，O(1) 查询 | O(n²) | 已接受 |

 ## 算法演练

 1. 读取整数$n, r, c$。 这些定义了板的尺寸和我们关心的确切位置。 
2. 阅读$n \times n$将网格转化为二维结构。 每行都被存储，以便我们稍后可以在恒定时间内访问任何单元格。 
3. 确保每行都正确拆分为单独的单元格。 这是必要的，因为输入使用空格分隔的字符。 
4. 访问所在行的单元格$r$， 柱子$c$。 
5. 如果该单元格的值为“S”，则输出“No”，因为船只被击中。 
6. 否则输出“Yes”，表示海洋，因此未命中。 

即使我们只需要一个单元格，读取整个网格背后的关键思想是输入仍然必须被完全消耗。 竞争性编程限制始终需要完全摄取输入流。 

### 为什么它有效

 网格是游戏状态的直接表示。 每个坐标恰好对应一个单元格，没有歧义或隐藏变换。 由于查询不依赖于任何计算或邻居，因此正确性降低为正确解析输入并执行单个查找。 一旦索引正确，该算法就不会失败，因为不涉及聚合或推理。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, r, c = map(int, input().split())
    grid = []

    for _ in range(n):
        row = input().strip().split()
        grid.append(row)

    if grid[r][c] == 'S':
        print("No")
    else:
        print("Yes")

if __name__ == "__main__":
    main()
```该解决方案存储整个网格，因为输入必须逐行消耗。 每行都按空格分割，以正确提取单个单元格。 关键操作是直接查找`grid[r][c]`，它准确地反映了查询的位置。 

一个常见的实施错误是忘记`.split()`，这会导致该行被视为包含空格的单个字符串，从而破坏索引逻辑。 另一个问题是混合了行和列的顺序，因为网格在输入中自然是行优先的，但必须仔细解释坐标。

| 步骤| 行动| 价值|

| 步骤| 行动| 价值|

 | 2 | 访问网格[0] | 哦哦|
 | 3 | 检查第 2 栏 | 哦|

 由于单元格是海洋，因此输出为“是”。 

这证实了边界列处未命中的正确性。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n²) | 我们必须读取所有网格单元一次，并且查找时间为 O(1) |

 ## 边缘情况

 对于单单元板，该算法读取一行并直接访问`grid[0][0]`。 如果单元格为“O”，则输出“Yes”； 如果是“S”，则输出“No”。 由于统一应用相同的索引逻辑，因此不需要特殊情况处理。 

对于 (0,0) 或 (n-1,n-1) 等边界坐标，算法的行为相同。 例如，如果$n = 2$网格是：```
O O
O S
```查询为(1,1)，算法访问第二行第二列，找到“S”，并输出“No”。 这证实了不需要逐一调整，因为输入已经是从零开始的。
