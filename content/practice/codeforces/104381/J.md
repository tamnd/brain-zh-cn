 ## 解决方案
 ## 问题理解

 我们有两组人数相等的玩家，每组都包含$n$人们。 每个玩家都有一个评分。 主办方会将选手分成固定的A组和B组，但配对是灵活的：A组中的每个人必须与B组中的每个人恰好匹配，形成$n$2v2 团队。 

一个团队的实力是其两名成员评分的总和。 在给定配对中组成的所有球队中，锦标赛获胜者是总金额最大的球队。 然而，我们并没有被问及单个配对。 相反，我们会考虑所有可能的方式来完全匹配 A 和 B，并且对于每次匹配，我们都会考虑其最强的团队。 目标是在所有可能的匹配中最小化最强的球队。 

因此，我们通过在 A 和 B 之间选择巧妙的配对来有效地尝试控制最坏情况的最大对和。 

输入尺寸很大，可达$n = 10^5$，这立即排除了任何对匹配或配对比较的二次探索。 任何试图考虑所有配对甚至所有候选匹配的方法都将远远超出时间限制。 我们应该期待$O(n \log n)$或线性时间贪婪解决方案。 

天真的推理时会出现一个微妙的问题：在没有精确规则的情况下，很容易将大值与小值配对，但不同的“合理”启发法可以产生不同的最大对和，并且如果不仔细排序，最佳结构并不明显。 

例如，如果 A = [1, 10] 且 B = [1, 10]，则 (1,10) 和 (10,1) 配对给出最大值 11，而 (1,1) 和 (10,10) 配对给出最大值 20。配对策略完全改变了瓶颈。 

关键的困难在于我们不是最小化所有球队的总和，而是最小化匹配中的最大配对总和。 

## 方法

 暴力方法会尝试 B 的每个排列，并计算与 A 的每个配对的最大对和。这是正确的，因为它探索了两组之间所有可能的双射。 然而，有$n!$可能的匹配，并且对于每个我们计算$n$总和，导致$O(n \cdot n!)$运营。 即使对于非常小的情况，这也是不可行的$n$。 

问题的结构表明我们应该对值进行排序，然后构建一个平衡极端值的配对。 目的是防止任何单个对变得太大。 如果我们对两个数组进行排序，我们就可以控制极端情况如何相互作用。 

关键的观察结果是，最大对和是由一组中最大元素与另一组中最大元素如何相互作用驱动的。 如果我们将大与大配对，我们就会创造出大的峰值。 如果我们将大与小配对，我们就会更均匀地分配重量。 

思考这个问题的一个有用方法是想象固定一个阈值$T$。 我们想知道是否可以将元素配对以使每对和最多为$T$。 如果我们可以的话$T$是可行的。 最小可行$T$就是答案。 对于固定的$T$, 每个元素$a_i$必须与一些配对$b_j \le T - a_i$。 这就变成了匹配可行性问题，但是因为两边都是排序的，所以我们可以贪婪地检查可行性。 

然而，我们可以完全避免二分搜索。 对两个数组进行排序并将最小与最大的方向相反的配对可以直接平衡极端情况。 具体来说，将 A 中最小的元素与 B 中最大的元素配对，将第二小的元素与第二大的元素配对，依此类推，可确保没有一个元素对同时受两个大元素支配。 这种安排使最大总和最小化，因为将类似排序的元素配对的任何偏差只会增加至少一个极端总和。 

因此，在对 A 升序和 B 升序排序后，我们将$a[i]$和$b[n-1-i]$，并计算这些总和的最大值。 

这会产生最小可能的最大对和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n \cdot n!)$|$O(n)$| 太慢了|
 | 最优（排序+贪婪配对）|$O(n \log n)$|$O(1)$额外（忽略排序）| 已接受 |

 ## 算法演练

 我们现在直接构建最佳配对。 

1. 按非降序对数组 A 进行排序。 这使我们能够一致地推理出最弱和最强的元素。 
2. 出于同样的原因，以非降序对数组 B 进行排序。 
3. 初始化变量`answer = 0`跟踪遇到的最大对和。 
4. 对于每个索引$i$从 0 到$n-1$， 一对$a[i]$和$b[n-1-i]$。 计算它们的总和并更新`answer = max(answer, a[i] + b[n-1-i])`。 

反转 B 的原因是为了强制平衡效果：A 中的小元素与 B 中的大元素配对，防止一对的两边同时变大。 

1. 输出`answer`。 

### 为什么它有效

 排序之后，我们就有了全球的优势排序。 任何最佳匹配都必须以避免将大值聚集在一起的方式对元素进行配对。 如果两个大元素配对，则该对成为最大值的候选者。 通过将一侧的最大元素与另一侧的最小元素配对，我们确保与任何替代重新排列相比，没有一对可以“比必要的更糟糕”。 任何将较大的 B 元素移近较大的 A 元素的交换只能增加或保留最大对和，而绝不能减少它。 这个交换参数保证了反向配对是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    a.sort()
    b.sort()
    
    ans = 0
    for i in range(n):
        ans = max(ans, a[i] + b[n - 1 - i])
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案完全依赖于对两个数组进行排序，然后执行单个线性扫描。 配对逻辑是在循环中实现的，其中索引有意跨数组 B 进行镜像。关键细节是使用`n - 1 - i`，这确保 B 中的最大值与 A 中的最小值配对。 

不需要额外的数据结构，并且除排序之外的所有计算都是线性的。

 ## 边缘情况

 最小输入$n = 1$由一对组成。 该算法对两个数组进行排序并直接计算唯一可能配对的总和。 由于没有替代匹配，因此输出基本上是正确的。 

在所有值都相等的情况下，排序不起作用。 每个配对都会产生相同的总和，并且算法返回该值的两倍，这与真正的最大值匹配。 

对于严格递增的数组，反向配对强制最小与最大，确保最大值是由中间相互作用而不是极端对齐确定的。 这可以防止出现最坏的情况，即同一对中较大的值相互增强。
