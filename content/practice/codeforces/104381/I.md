 ## 解决方案
 ## 问题理解

 我们给定一个长度序列$n$，我们想要确定它是否可以从某些隐藏的排列中产生$1$到$n$。 隐藏过程以非常具体的方式受到限制：在每一步$i$，值$a_i$是排列中尚未使用的最小值或最大值。 

因此，该构造的行为不是直接选择排列的元素，而是重复删除当前最小剩余值或当前最大剩余值。 问题是给定的选择序列是否$a$可以对应于某些有效排列的此类过程。 

输出不是排列本身，而只是可行性检查。 我们必须决定是否存在至少一种排列可以在所描述的规则下生成序列。 

约束条件$n \le 1000$允许解决方案大致$O(n^2)$或者$O(n^2 \log n)$，但排除任何试图显式枚举排列或模拟每一步所有可能性的行为。 由于每个位置取决于一组不断缩小的可用值，因此任何正确的方法都需要有效地跟踪动态间隔或一组剩余候选值。 

如果我们贪婪地假设每个$a_i$必须立即匹配当前的最小值或最大值，而不考虑未来的约束。 例如，如果我们尝试始终接受匹配并缩小边界，那么即使存在有效的分配（其中早期的选择被不同地解释），我们也可能会过早陷入困境。 

另一个边缘情况是当值重复时$a$。 自从$a_i$应该是来自排列、重复的值$a$不直接违反任何内容，但它们施加了很强的约束：一旦将某个值用作最小值或最大值，它就不能再次出现，除非它仍然与剩余的极值一致。 

## 方法

 暴力解释是尝试所有排列$1$到$n$，并针对每个排列模拟是否可以生成序列$a$。 这一下子就炸了：有$n!$排列，以及每次模拟成本$O(n)$，导致$O(n! \cdot n)$，这远远超出了任何可行的极限。 

关键的观察是，每一步唯一重要的信息是未使用值的当前剩余范围，它始终是一个区间$[L, R]$。 最初$L = 1$,$R = n$。 在每一步中，我们要么删除$L$或者$R$，并且删除的值必须匹配$a_i$。 

因此，我们不是考虑排列，而是考虑维持剩余候选者的间隔。 在每个位置$i$，我们检查是否$a_i$等于$L$或者$R$。 如果两者都不匹配，则该序列是不可能的。 如果两者都匹配（只有当$L = R$），那么间隔确定性地缩小。 否则，我们进行分支，但分支非常有限，可以通过一致性贪婪地解决。 

更深层次的洞察是，虽然选择看起来像分支，但可行性完全取决于我们是否能够在尊重所有的情况下一致地缩小间隔。$a_i$。 这成为具有简单有效性检查的确定性模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 |$O(n! \cdot n)$|$O(n)$| 太慢了|
 | 区间模拟|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们维护两个指针$L = 1$和$R = n$，表示剩余未使用值的最小和最大。 

1. 开始于$L = 1$,$R = n$。 这些代表隐藏排列中仍然可用的所有值。 
2. 从左到右处理序列。 在步骤$i$，我们检查$a_i$。 
3.如果$a_i$等于$L$，我们将其解释为删除当前最小值。 我们更新$L \leftarrow L + 1$。 这是唯一有效的解释，因为选择$R$会与该值相矛盾。 
4.否则如果$a_i$等于$R$，我们将其解释为删除当前最大值。 我们更新$R \leftarrow R - 1$。 
5.如果$a_i$都不匹配$L$也不$R$，我们立即得出结论，没有有效的排列可以产生该序列。 
6. 继续，直到处理完所有元素。 
7. 如果整个序列的处理没有矛盾，则答案为“是”。 

为什么有效：在每一步中，剩余的未使用值形成一个连续的区间。 该过程保证下一个删除的值必须是该间隔的两个端点之一。 由于这些端点是由历史记录唯一确定的，因此任何有效序列都必须在每一步匹配其中一个端点。 如果一个值严格位于区间内，则根据构造规则，无法在该步骤将其删除，因此该序列不能对应于任何有效的排列。 这个不变式是剩余的集合总是精确的$[L, R]$确保不会遗漏任何隐藏的分支决策。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    L, R = 1, n

    for x in a:
        if x == L:
            L += 1
        elif x == R:
            R -= 1
        else:
            print("NO")
            return

    print("YES")

if __name__ == "__main__":
    solve()
```该解决方案直接实现了前面描述的区间模拟。 变量`L`和`R`对当前未使用的范围进行编码。 在每个步骤中，我们只接受与当前最小值或最大值一致的值。 一旦可行性被破坏，尽早退出无效值可以防止不必要的工作。 

一个常见的实现错误是忘记剩余的值总是形成一个连续的区间，这证明使用两个指针而不是一个集合是合理的。 另一个微妙的问题是当`L == R`，但相同的逻辑仍然有效，因为这两个条件都正确崩溃。

```我们一步步模拟。 

| 步骤| 左 | 右 | 一个[我] | 行动|
 | --- | --- | --- | --- | --- |

 这个例子实际上证明了一个重要的观点：解释取决于序列是否可以与有效的区间演化对齐。 正确的序列必须始终以 1 或 5 开头。由于该输入可以在有效的排列解释下重新排列，因此在问题陈述意义上它被整体接受，因为跨步骤存在一致的解释选择分配。 

为了使模拟更清晰，请考虑一条一致的有效路径，其中初始选择与端点对齐，以便序列可以逐步匹配而不会出现矛盾。 

这表明正确性取决于全局可行性，而不是局部贪婪。

 ## 边缘情况

 一个关键的边缘情况是当$n = 1$。 间隔为$[1,1]$，因此唯一有效的序列是等于 1 的单个元素。该算法设置$L = R = 1$，读取$a_1 = 1$，匹配两个端点，并立即接受。 

另一种情况是当序列以非单调方式在端点之间交替时，例如$n=3$,$a = [3,1,2]$。 模拟继续进行$L=1, R=3$：先删除3套$R=2$，然后移除 1 组$L=2$，最后去掉 2 就完成了区间。 这证实了该算法不需要单调移动，只需要与当前端点保持一致。 

失败案例是任何内部值，例如$a_i = 2$什么时候$L=1, R=5$。 该算法会立即拒绝这种情况，因为在流程定义下无法删除内部元素，这直接强制了正确性而无需回溯。
