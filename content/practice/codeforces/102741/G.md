 ## 解决方案
 ## 问题理解

 我们得到了一块由小写字母组成的矩形板。 每行都是一个字符串，我们可以从板上删除整列。 目标是删除尽可能少的列，以便在将剩余的列连接在一起后，行从上到下按非递减的字典顺序显示。 原始任务要求必须消失的最小列数。 

重要的细节是删除一列会影响同一位置的每一行。 我们不允许重新排列行或编辑单个字符。 对于一对相邻行来说看起来不好的列可能对其他行仍然有用，因此决策必须一起考虑所有相邻行的比较。 

约束条件决定了可能的策略。 如果网格周围有$10^5$单元格中，我们可以对每个字符进行固定次数的检查。 任何尝试列的每个子集的解决方案都是不可能的，因为子集的数量是指数级的。 即使尝试所有可能的列顺序或在每次删除后重复重建网格也会太慢。 该解决方案需要在扫描一次网格的同时做出本地决策。 

一些边缘情况可能会破坏粗心的实现。 如果所有行都已排序，则不应删除任何列。 

输入示例：```
3 3
abc
abd
acd
```正确的输出是：```
0
```删除某处包含减少的每一列的解决方案将删除不必要的列，因为第一列已经正确分隔了行。 

另一个棘手的情况是当两行在后面的列之前排序时。 

输入示例：```
3 3
abc
bbc
bba
```正确的输出是：```
1
```第一列证明第一行小于第二行和第三行。 仅保留第二行和第三行之间的比较，最后一列会产生冲突。 持续检查已解析的行对的解决方案可能会错误地删除更多列。 

最后的边缘情况是存在相等的行。 

输入示例：```
2 3
aaa
aaa
```正确的输出是：```
0
```相等的行已经有效，因为所需的顺序是非递减的，而不是严格递增的。 

## 方法

 直接的方法是尝试删除列并测试剩余的网格是否已排序。 对于每个可能的删除列集，我们可以构建结果行并按字典顺序比较相邻行。 这是正确的，因为它准确地检查了问题所需的条件。 然而，随着$m$列有$2^m$可能的选择，因此检查的数量呈指数级增长。 即使网格很小，这也很快变得不可能。 

稍微更好的尝试是逐一检查列，并删除其中某些相邻对在较小字符上方具有较大字符的任何列。 问题在于，并非所有比较都需要永远考虑。 Once an earlier kept column proves that row$i$小于行$i+1$，未来的列不能改变这种关系。 继续将这一对视为可能的冲突根源会导致不必要的删除。 

关键的观察是字典顺序比较仅取决于两行不同的第一列。 当从左到右扫描列时，我们可以记住哪些相邻行对已经由前面的列决定了。 对于当前列，冲突仅存在于未解决的对之间。 如果当前列使任何未解析的对减少，则该列无法保留。 否则，保留它总是安全的，并且每个严格递增的未解决对都可以标记为已解决。 

暴力破解之所以有效，是因为它反复询问当前选择的列是否创建了有效的排序，但会失败，因为它忽略了许多行比较已永久解决的事实。 对解析的相邻对的观察将问题简化为单个贪婪扫描。

 | 蛮力 |$O(2^m \cdot nm)$|$O(nm)$| 太慢了|

 ## 算法演练

 1. 读取网格并创建一个数组，该数组表示是否已确定每个相邻行对的顺序正确。 

一对相邻的行只需要关注，直到某些保留的列证明上面的行更小。 此后，后面的列不能使该对无效。 
2. 从左到右扫描列。 

左边的列在词典比较中具有更高的优先级，因此必须在查看后面的列之前做出关于列的决定。 
3. 对于当前列，检查未解析的每个相邻行对。 

如果上一行中的字符大于其下一行中的字符，则保留此列将使最终排序变得不可能。 必须删除该列。 
4. 如果该列没有产生冲突，则保留它并更新已解决的对。 

每当未解析的对在上行中的字符小于在下行中的字符时，该对现在将被永久排序并且不需要将来的检查。 
5. 计算每个被拒绝的列并输出该计数。 

被拒绝的列正是不能参与任何有效解决方案的列。 

为什么它有效：

 该算法保持了这样的不变性：仅使用迄今为止处理的保留列，每个已解析的相邻对都已正确排序。 对于未解析的对，所有先前保留的列都包含相同的字符，因此当前列是可以确定该对的第一个可能位置。 如果它减少，则未来的列无法修复排序，因为字典顺序已经被错误地确定。 如果增加，该货币对将永久有效。 由于每列只要不违反任何未解决的比较就会被保留，因此该算法仅删除被迫删除的列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    resolved = [False] * (n - 1)
    answer = 0

    for col in range(m):
        bad = False

        for row in range(n - 1):
            if not resolved[row] and grid[row][col] > grid[row + 1][col]:
                bad = True
                break

        if bad:
            answer += 1
            continue

        for row in range(n - 1):
            if not resolved[row] and grid[row][col] < grid[row + 1][col]:
                resolved[row] = True

    print(answer)

if __name__ == "__main__":
    solve()
```这`resolved`数组存储每个相邻行比较的状态。 它的长度是`n - 1`因为行只需要与紧邻其下方的行进行比较。 

对于每一列，代码首先检查是否存在矛盾。 这必须在更新之前发生`resolved`，因为删除的列不会影响排序。 如果不存在矛盾，则第二个循环标记新确定的比较。 

该实现从不构造剩余的网格，这避免了不必要的复制。 它仅读取每个单元格恒定的次数，匹配网格上所需的线性扫描。 边界条件`n - 1`也很重要，因为最后一行之后没有相邻对。

 ## 边缘情况

 对于已经排序的情况：```
3 3
abc
abd
acd
```第一列解析第一次比较，第二列解析第二次比较。 最后一列永远不会产生冲突，因为两对都已经决定了。 算法输出`0`。 

对于一对在另一对之前解决的情况：```
3 3
abc
bbc
bba
```第一列永久固定第一行和第二行之间的关系。 第二行和第三行一直悬而未决，直到最后一列，它们的顺序变得不正确。 该算法仅删除该列并输出`1`。 

对于相等的行：```
2 3
aaa
aaa
```每个比较仍然悬而未决，因为没有列创建严格的排序，但也没有列创建冲突。 该算法保留所有列和输出`0`，正确地将相等的行视为有效。 

对于多次强制删除：```
3 3
cba
bca
abc
```扫描发现前两列中未解决的对之间存在冲突。 每个冲突的列都会立即删除，而算法会不断检查后面的列与剩余的未解决的比较。 这证实了每个删除决定仅基于未来列无法修复的信息。
