 ## 解决方案
 ## 问题理解

 地图是一个由山丘组成的网格。 迈克尔从顶部边缘的某处开始，每分钟向下移动一行，而特雷弗从左边缘的某处开始，每分钟向右移动一列。 每次移动最多允许横向调整一个单元，因此迈克尔可以在下降时向左或向右漂移，而特雷弗可以在前进时向上或向下漂移。 他们希望同时在同一个牢房见面，分数是每个骑手访问的每座山的高度之和。 如果两个骑手都访问同一座山，则其价值会被计算两次。 

约束最多允许 1000 行和 1000 列，因此可以有 100 万个单元格。 每个单元完成的工作量超过少量恒定工作量的解决方案不太可能适合。 特别是，尝试每对可能的路径是不可能的，因为路径的数量呈指数增长。 即使是一个对两个骑手的位置都有额外维度的动态程序，也会有大约一万亿个状态，这远远超出了限制。 有用的目标是 O(nm) 或 O(nm log n) 解决方案。 

主要的边缘情况来自起始位置的自由以及起始位置的会议是有效的这一事实。 假设两名车手从同一个弯角出发的解决方案会失去有效答案。 

例如：```
1 3
5 1 1
```正确的输出是：```
10
```两名乘客都可以从唯一可用的排开始，并立即在他们选择的第一个单元汇合。 一个粗心的解决方案会迫使会议在至少一个动作之后举行，这样就会错过这个案例。 

另一种情况是：```
2 2
1 1
2 2
```正确的输出是：```
7
```最好的选择是 Michael 穿过值 1 和 2，而 Trevor 从左下角的值 2 开始，到达另一个值 2 的会议单元格。共享的山丘对两个骑手都计算在内，因此从总和中删除重复值会给出错误的答案。 

## 方法

 一种直接的方法是枚举一个集合点并计算每个骑手到达该集合点的最佳路线。 对于每个可能的会议单元，我们可以从起始边缘开始搜索。 这是正确的，因为两个骑手在相遇之前是独立移动的。 然而，重复搜索每个可能的交汇点，每个点执行大约 O(nm) 的工作，导致最坏情况下的 O(n²m²) 操作，这对于具有 100 万个单元的网格来说太慢了。 

关键的观察是骑手的运动有固定的方向。 Michael 的行每分钟恰好增加 1，因此到达单元格仅取决于前一行。 Trevor 的列每分钟恰好增加 1，因此到达单元格仅取决于前一列。 这两个独立的路径问题可以用动态规划分别求解。 

我们计算一个 DP 表，其中包含 Michael 在到达每个单元格时可以获得的最佳分数。 第二个 DP 表包含 Trevor 在到达每个单元格时可以获得的最佳分数。 只有当两个乘客可以同时到达某个小区时，该小区才能成为集合点。 构建两个表后，答案就是所有可能的会议单元格中两个值的最大总和。 

蛮力之所以有效，是因为它探索了每对可能的路线，但它多次重复相同的子问题。 观察到每个骑手只有一个变化的坐标，我们可以将这些重复计算折叠成两个线性网格通道。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²m²) | O(纳米) | 太慢了|
 | 最佳 | O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 1. 构建 Michael 的动态规划表。 对于顶行，每个单元格都是可能的起始位置，因此初始值只是该单元格的高度。 对于后面的每一行，输入单元格的最佳方式来自其正上方对角线或垂直方向的三个单元格之一。 获取先前的最佳值后添加当前的山高度。 
2. 构建Trevor 的动态规划表。 对于左列，每个单元格都可以是起始位置。 对于后面的每一列，前一个位置必须位于前一列中，并且可以是上面一行、同一行或下面一行。 将当前的山高度添加到之前的最佳分数中。 
3. 检查两个乘客可以同时到达的每个单元格。 仅当 Michael 进行了 i 步并且 Trevor 进行了 j 步时，才可能在第 i 行和第 j 列相遇，因此我们需要 i = j。 答案是这些对角单元格上迈克尔的值加上特雷弗的值的最大值。 
4. 返回找到的最高分数。 由于考虑了对角单元 (0,0)，因此自然包括两个骑手一起出发的情况。 

工作原理：单元格的 Michael DP 值存储了结束于此的所有有效向下路径中可能的最佳分数。 过渡考虑了每一个可能的最终动作，因此不会错过更好的路径。 同样的论点也适用于 Trevor 的 DP。 由于乘客在会合前不会影响彼此的移动，因此所选会合单元的最佳路线对恰好是两个独立 DP 值的总和。 取所有有效会议单元格中的最大值即可得出最佳总分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]

    michael = [[0] * m for _ in range(n)]
    for j in range(m):
        michael[0][j] = grid[0][j]

    for i in range(1, n):
        for j in range(m):
            best = michael[i - 1][j]
            if j > 0:
                best = max(best, michael[i - 1][j - 1])
            if j + 1 < m:
                best = max(best, michael[i - 1][j + 1])
            michael[i][j] = best + grid[i][j]

    trevor = [[0] * m for _ in range(n)]
    for i in range(n):
        trevor[i][0] = grid[i][0]

    for j in range(1, m):
        for i in range(n):
            best = trevor[i][j - 1]
            if i > 0:
                best = max(best, trevor[i - 1][j - 1])
            if i + 1 < n:
                best = max(best, trevor[i + 1][j - 1])
            trevor[i][j] = best + grid[i][j]

    ans = 0
    for i in range(min(n, m)):
        ans = max(ans, michael[i][i] + trevor[i][i])

    print(ans)

if __name__ == "__main__":
    solve()
```第一个 DP 传球遵循 Michael 的移动规则。 第一行直接初始化，因为他可以选择任何顶行起始位置。 转换仅查看前一行，与他必须每分钟向下移动的事实相匹配。 

第二个 DP 通道是相同的想法，但旋转了 90 度。 Trevor 的时间维度是列号，因此每个转换都来自前一列。 初始化左列中的每个单元格是必要的，因为 Trevor 可以沿着该边缘的任何位置开始。 

最后的循环仅检查单元格`(i, i)`。 时`i`, 迈克尔必须在排`i`特雷弗一定在专栏里`i`，因此任何其他单元格都不能成为同时会议位置。 使用 Python 整数可以避免溢出，因为最大分数可能比 32 位整数大得多。

 对于第一个样本：```

1 1
2 2
```迈克尔的表变成：

 | 细胞| 价值|
 | ---| ---|
 | (0,0) | (0,0) | 1 |
 | (0,1)| 1 |
 | (1,0)| 3 |

 Trevor 的表变为：

 | 细胞| 价值|
 | ---| ---|
 | (0,0) | (0,0) | 1 |
 | (1,0)| 2 |
 | (0,1)| 2 |
 | (1,1) | 4 |

 可能的会议单元是`(0,0)`和`(1,1)`。 他们的分数分别是 2 和 7，因此答案是 7。此迹线显示了为什么共享山丘被计算两次。 

对于第二个样本：```
3 3
1 2 3
4 5 6
7 8 9
```对角线状态是：

 | 位置 | 迈克尔得分 | 特雷弗得分 | 合并 |

 | (2,2) | 17 | 17 25 | 25 42 | 42

 最佳交汇点是右下角的单元格，生成 42。该轨迹表明最佳交汇点不一定要早。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(纳米) | 每个DP表处理每个网格单元一次。 |
 | 空间| O(纳米) | 两张表存储了两位骑手的最佳成绩。 |

 对于最多一百万个单元，该解决方案仅执行几百万次操作，并且可以轻松满足给定的限制。

 ## 边缘情况

 对于立即会议的情况：```
1 1
10
```两名车手都从唯一的一座山上出发。 DP 表都包含 10 个 at`(0,0)`，最终答案检查该单元格，生成 20。不需要移动。 

对于共享起始边缘情况：```
2 2
1 1
2 2
```该算法在检查答案之前不会强制移动。 它评估`(0,0)`作为有效的会面点并评估`(1,1)`，最佳路径相遇的地方。 第二个选项给出 7。 

对于长方形的情况：```
2 3
5 1 1
1 1 1
```对角线会议位置仅`(0,0)`和`(1,1)`，因为两个骑手必须采取相同的步数。 该算法永远不会访问超出较小维度的无效对角线位置，从而防止出现越界错误。
