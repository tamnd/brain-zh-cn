 ## 解决方案
 ## 问题理解

 该问题将沙拉类型描述为整数`1`到`10^8`。 每种类型都有一个由特殊舍入规则确定的价格：类型的价格`x`是大于或等于的最小数`x`其十进制表示仅包含数字`3`和`8`。 我们需要找到给定包含区间内每种沙拉类型的总价格`[l, r]`。 

看待这个问题的有用方法是，每种沙拉类型的价格函数都不会改变。 它在长距离内保持不变，只有当我们通过幸运数字时才会跳跃。 例如，所有值来自`4`到`8`有价格`8`， 因为`8`是他们收到的第一个幸运数字。 

的上限`10^8`排除迭代间隔内的每种沙拉类型。 一个范围可以包含一亿个值，甚至一个`O(r-l+1)`在一秒的限制内解决方案会太慢。 我们需要利用极少数的幸运数字。 因为每个幸运数字都是由数字组成的`3`和`8`，只有`2^k`幸运数字与`k`数字。 即使考虑到所有九位数字的幸运数字也只能给出几百个候选者。 

一些边缘情况可能会破坏直接实现。 一个常见的错误是忘记幸运数字本身属于其自己的价格段。 例如：```
Input:
3 3

Output:
3
```唯一的沙拉类型是`3`，它的价格正好是`3`。 在幸运数字之后开始一个段的实现会错误地跳过该值。 

当右端点不是幸运数字时，就会出现另一个问题。 例如：```
Input:
7 7

Output:
8
```之后的下一个幸运数字`7`是`8`，所以答案是`8`。 仅对区间内的幸运数字求和的解决方案将返回零。 

当间隔在段的中间结束时，会发生第三种边界情况。 例如：```
Input:
2 34

Output:
909
```该段结束于`33`仅在达到之前的最后一个幸运数字后才需要部分`34`。 该算法必须使用下一个幸运数字添加剩余值，而不是继续搜索另一个完整的段。 

## 方法

 暴力解法直接遵循定义。 适合每种沙拉类型`x`在`[l, r]`，我们寻找第一个至少是的幸运数字`x`，将其添加到答案中，然后继续。 这是正确的，因为每个单独的价格都是按照描述精确计算的。 

问题是这会多次重复几乎相同的工作。 如果区间包含`10^8`值并且每次查找都会检查几个幸运数字，操作计数变得太大。 如果对时间间隔内的每个值执行一次，即使经过优化的查找仍然会太慢。 

关键的观察结果是价格函数仅在幸运数字处发生变化。 假设两个连续的幸运数字是`8`和`33`。 每个值来自`9`通过`33`具有相同的价格，`33`。 我们可以一次处理整个段，而不是单独处理这些值。 

蛮力方法之所以有效，是因为每个单独的价格都可以独立计算，但它会失败，因为单独的值太多。 观察到幸运数字的数量很少，让我们一次构建所有段，然后仅对与`[l, r]`。 

最简洁的实现是构建一个前缀函数。 让`sum(n)`是沙拉类型的总成本`1`到`n`。 那么所需的答案是：```
sum(r) - sum(l - 1)
```计算`sum(n)`，生成所有幸运数字，对它们进行排序，并遍历它们的片段。 为了一个幸运数字`x`，贡献的部分`x`是从上一个幸运数字加一到`x`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O((r-l+1) * L) | O(L) | 太慢了|
 | 最佳 | O(L log L) | O(L log L) | O(L) | 已接受 |

 这里`L`是生成的幸运数字的数量，只有几百个。 

## 算法演练

 1. 生成每个相关的幸运数字。 从空前缀开始并递归附加任一数字`3`或数字`8`。 达到超过九位数字后停止，因为对于给定的限制来说，上面的值是不必要的。 

生成的数字很少，因此显式生成它们比尝试手动推理小数情况更简单、更安全。 

1. 将生成的幸运数字按升序排列。 

等价段取决于连续的幸运数字，因此必须从小到大进行处理。 

1. 构建前缀和函数`sum(n)`。 保留一个代表先前幸运数字的变量，最初为零。 对于每个幸运数字`x`，值来自`previous + 1`到`x`都有价格`x`。 

整个部分的贡献是：```
(number of values) * x
```如果`n`落在该段内，只有来自的值`previous + 1`到`n`被计数并且该过程停止。 

1. 将最终答案计算为`sum(r) - sum(l - 1)`。 

这会将一个区间查询转换为两个前缀查询，避免对左边界进行特殊处理。 

为什么它有效：

 每个正整数都有一个至少是其自身的第一个幸运数字。 在两个连续的幸运数字之间，第一个幸运数字对于区间内的每个值都是相同的。 该算法将所有整数精确地划分为这些段，并将每个段的贡献相加一次。 由于前缀计算包括来自的每个值`1`到`n`正好一次，减去两个前缀就得到了所请求的间隔总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def generate_lucky(cur, lucky):
    if cur > 10**9:
        return
    if cur:
        lucky.append(cur)
    generate_lucky(cur * 10 + 3, lucky)
    generate_lucky(cur * 10 + 8, lucky)

lucky = []
generate_lucky(0, lucky)
lucky.sort()

def prefix_sum(n):
    if n <= 0:
        return 0

    ans = 0
    prev = 0

    for x in lucky:
        if prev >= n:
            break

        right = min(n, x)
        if right > prev:
            ans += (right - prev) * x

        prev = x

    return ans

def solve():
    l, r = map(int, input().split())
    print(prefix_sum(r) - prefix_sum(l - 1))

if __name__ == "__main__":
    solve()
```递归生成器通过在每一级附加一个有效数字来创建所有幸运数字。 停止条件允许值略高于`10^8`，因为该算法需要在最大可能的沙拉类型之后的第一个幸运数字。 

这`prefix_sum`函数扫描排序后的幸运数字，并将每个数字视为固定价格段的末尾。 变量`prev`存储最后一个幸运数字，因此当前段开始于`prev + 1`。 乘法使用 Python 整数，它会自动处理较大的最终答案。 

这`min(n, x)`操作是重要的边界细节。 如果前缀端点位于幸运数字之前，则仅应包含该段的一部分。 如果没有此检查，该函数将超出计算值`n`。 

## 工作示例

 对于第一个例子：```
Input:
3 9
```需要的幸运数字是`3`,`8`， 和`33`。 

| 步骤| 幸运数字| 上一个幸运儿 | 添加范围 | 贡献| 当前总计 |
 | ---| ---| ---| ---| ---| ---|
 | 1 | 3 | 0 | 1 至 3 | 3 × 3 = 9 | 3 × 3 = 9 9 |
 | 2 | 8 | 3 | 4 至 8 | 5 × 8 = 40 | 5 × 8 = 40 49 | 49
 | 3 | 33 | 33 8 | 9 到 9 | 1 × 33 = 33 | 1 × 33 = 33 | 82 | 82

 前缀计算给出`sum(9) = 82`。 间隔开始于`3`，所以减去`sum(2)`消除类型的成本`1`和`2`，两者都是`3`。 最终的答案是`82 - 6 = 76`。 

对于第二个例子：```
Input:
7 7
```前缀计算为：

 | 查询 | 幸运数字段已达| 增值 | 结果 |
 | ---| ---| ---| ---|
 | 总和(7) | 1到3成本3，4到7成本8 | 9+32| 41 | 41
 | 总和(6) | 1到3成本3，4到6成本8 | 9+24| 33 | 33

 答案是`41 - 33 = 8`。 这表明价值本身并不需要是幸运的。 价格来自下一个幸运数字。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(L log L) | O(L log L) | 生成和排序一小组幸运数字是这项工作的主导部分。 每个前缀查询都会扫描同一组一次。 |
 | 空间| O(L) | 该算法仅存储生成的幸运数字。 |

 即使生成超出最大输入值，幸运数字也不足千个。 该解决方案很容易满足时间和内存限制，因为它从不依赖于间隔的大小。

 ## 边缘情况

 对于单一幸运值的情况：```
Input:
3 3
```该算法考虑以幸运数字结尾的第一段`3`。 该段内的范围仅为`1`到`3`，但前缀差异只保留值`3`。 结果是`3`。 

对于幸运数字之前的值：```
Input:
7 7
```前缀函数放置`7`段内来自`4`到`8`。 分段价格为`8`，所以答案是`8`。 该算法从不假设端点必须是幸运数字。 

对于跨越线段边界的区间：```
Input:
7 9
```价值`7`和`8`属于定价为`8`， 尽管`9`属于下一个细分市场，定价为`33`。 

计算公式为：```
8 + 8 + 33 = 49
```基于分段的方法处理转换，因为它独立地处理与每个幸运数字间隔的重叠。 

对于最大边界：```
Input:
100000000 100000000
```下一个幸运数字是`333333333`。 该算法生成了超出输入范围的幸运数字，因此它可以正确识别价格，而不是找不到有效值。
