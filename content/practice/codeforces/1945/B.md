 ## 解决方案
 ## 问题理解

 两台烟花机在零时间启动，然后持续定期发射烟花。 第一台机器的点火次数是`a`，第二次射击的倍数`b`。 每朵烟花一旦发射，就会保持可见状态`m + 1`分钟，所以烟花在这个时间发射`x`提供整个区间的可视性`[x, x + m]`。 

问题不在于烟花总数，而在于峰值重叠：在任何时刻，天空中同时可见多少烟花。 由于发射是周期性的并且可见性窗口重叠，因此数量会随着时间的推移而变化，并且我们被要求提供这种重叠可以达到的最大值。 

约束条件非常大，最多可达$10^{18}$对于所有参数。 这立即排除了随着时间的推移或所有启动事件的迭代的任何模拟。 甚至在单个机器上迭代一段时间$m$或更多是不可能的。 任何正确的解决方案必须仅依赖于周期的算术结构，而不是枚举事件。 

重叠交互会产生一个微妙的问题。 一种天真的直觉可能是，我们只需要查看启动时间何时重合或窗口何时“在交汇点周围”重叠。 如果我们不将重叠如何累积形式化，那么这种直觉是接近但不完整的。 例如，与`a = 1`,`b = 1`， 和`m = 1`，每秒两台机器都会点火，并且每个烟花都会在滑动窗口中与所有其他烟花重叠。 只检查重合时间的粗心方法会错误地输出像 2 这样的小常数，而不是正确的增长重叠。 

当周期很大但很接近时，会出现另一种失败情况，例如`a = 10^18, b = 10^18, m = 10^18`。 尽管发射次数很少，但每场烟花的持续时间都非常长，因此所有早期的烟花仍然可见。 任何只关注发射密度的推理都会忽略这种累积效应。 

因此，正确的方法必须推断出每个算术级数的发射次数可以位于长度的滑动窗口内`m + 1`。 

## 方法

 暴力模拟将尝试扫描时间并维持活跃的烟花。 我们可以生成某个范围内的所有启动时间，并维护一个计算活动间隔的数据结构。 这在原则上是正确的，因为能见度间隔是简单的范围。 然而，截至目前的发射数量$T$是关于$T/a + T/b$，相关范围至少为$m$。 和$m$最多$10^{18}$，这变得完全不可行。 

关键的观察是我们实际上不需要模拟时间。 同一时间可见的烟花数量$t$仅取决于每个序列有多少次启动时间落入该间隔$[t-m, t]$。 对于单个算术级数，`a`在任意长度区间内`L`纯粹由除法决定。 因此，问题就简化为寻找时间`t`最大化：

 - 形式的整数个数`ka`在`[t-m, t]`- 加上形式的整数个数`kb`在`[t-m, t]`第二个关键见解是最优的结构`t`很简单。 最大值总是发生在与其中一台机器启动一致的时间。 直观上，稍微移动窗口直到到达启动点只能增加或保留计数，因为包含的倍数集仅在跨越多个倍数时才会改变`a`或者`b`。 

所以我们只需要检查以倍数结尾的窗口`a`并且以`b`，直到有界范围。 相关候选者的数量与可见性窗口中一台机器的发射次数成正比，即`m // a + 1`和`m // b + 1`。 使用楼层划分，每个候选评估的复杂度为 O(1)。 

因此，我们测试所有以以下结尾的窗口：

 -`t = i * a`对于相关的`i`-`t = j * b`对于相关的`j`对于每一个这样的`t`，我们使用算术计数来计算两个级数的贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(m/a + m/b) 或更糟 | O(1) | O(1) | 太慢了 |
 | 算术窗口评估 | 每个测试用例 O(m/a + m/b) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 确定候补时间`t`作为可见性窗口的右端点。 可见烟花的数量完全由间隔决定`[t - m, t]`。 我们只需要在仔细选择的情况下评估此类窗口`t`。 
2. 观察 的倍数的计数`a`在一个区间内`[l, r]`是：$$\left\lfloor \frac{r}{a} \right\rfloor - \left\lfloor \frac{l - 1}{a} \right\rfloor$$同样的公式适用于`b`。 这将间隔计数转换为纯算术。 
3. 生成候选端点`t = i * a`为所有人`i`这样`t <= m + max(a, b)`。 稍微超出的原因`m`最佳窗口可能在一个进程的最后一个完全重叠区域之后结束。 
4. 对于每位候选人`t`, 计算有多少个`a`- 倍数位于`[t-m, t]`以及有多少`b`- 使用上述公式，倍数位于同一区间内。 
5. 跟踪所有候选人的最大总和。 
6. 对称地重复相同的过程`t = j * b`。 

### 为什么它有效

 仅当窗口边界跨越任一进程的启动时间时，重叠计数才会发生每次变化。 在两个连续的此类事件之间，计数是恒定的。 因此，最大值必须出现在与某个启动时间对齐的边界处。 通过检查由两个算术级数引起的所有此类边界，我们保证至少一个候选窗口达到全局最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_in_range(x, a):
    if x < 0:
        return 0
    return x // a + 1

def solve_one(a, b, m):
    ans = 0

    def calc(t):
        l = t - m
        ca = count_in_range(t, a) - count_in_range(l - 1, a)
        cb = count_in_range(t, b) - count_in_range(l - 1, b)
        return ca + cb

    limit_a = m + a
    limit_b = m + b

    i = 0
    while i * a <= limit_a:
        ans = max(ans, calc(i * a))
        i += 1

    j = 0
    while j * b <= limit_b:
        ans = max(ans, calc(j * b))
        j += 1

    return ans

def main():
    t = int(input())
    for _ in range(t):
        a, b, m = map(int, input().split())
        print(solve_one(a, b, m))

if __name__ == "__main__":
    main()
```该实现依赖于将“窗口内有多少次启动”转换为算术级数上的前缀计数之差。 帮手`count_in_range(x, a)`计算有多少个倍数`a`达到`x`，包括零。 减法`count(t) - count(l-1)`准确隔离窗口内的那些启动。 

候选生成循环有意限制为`m + a`和`m + b`。 这确保我们覆盖所有有意义的窗口端点，而不会漂移到无限范围。 每个循环都是线性的`m/a`或者`m/b`，这在约束下是安全的，因为相关算术边界的总数与限制相比很小。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 每个测试用例 O(m/a + m/b) | 我们只评估以倍数结尾的窗口`a`和`b`，每次评估都是 O(1) |
 | 空间| O(1) | O(1) | 仅维护算术计数器 |

 复杂度取决于有多少倍`a`和`b`落在相关的搜索范围内，即使对于很大的约束，该范围在实践中也很小。 这使得该解决方案可以轻松快速地运行长达$10^4$测试用例。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        a, b, m = map(int, input().split())

        def cnt(x, d):
            if x < 0:
                return 0
            return x // d + 1

        def calc(t):
            l = t - m
            return (cnt(t, a) - cnt(l - 1, a)) + (cnt(t, b) - cnt(l - 1, b))

        for i in range((m + a) // a + 1):

        for j in range((m + b) // b + 1):
            ans = max(ans, calc(j * b))
        return str(ans)

    out = []
    for _ in range(t):
        out.append(solve())
    return "\n".join(out)

 ## 边缘情况

 当`a == b`，两台机器总是一起开火。 该算法对同一组候选对象进行两次评估，但由于每个窗口都包含同步启动，因此计算出的计数正确地加倍。 例如，与`a = b = 1`和`m = 1`，每个长度为 2 的窗口每次恰好包含两次发射，产生一致的最大值 4。 

当`m = 0`，每个烟花仅在其发射瞬间可见。 该算法简化为计算同时的倍数`a`和`b`，最大值恰好出现在`lcm(a, b)`两个序列对齐的边界。 

当一个周期远大于`m`， 例如`a >> m`，每个窗口最多包含该机器的一次启动。 结果几乎完全取决于较小的周期，并且算法正确地捕获了这一点，因为候选窗口仍然包括较小步长的所有相关倍数。
