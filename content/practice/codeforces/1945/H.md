 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，两个玩家将数组分成两组。 基里尔被允许选择一个既不太小也不太大的子集，特别是至少两个元素，最多$n-2$元素。 这些选定的元素形成红色组。 其他一切都变成蓝色组。 

一旦分割确定，分数就会以两种独立的方式计算。 在红色一侧，我们取所有选定数字的 GCD。 在蓝色一侧，我们对所有剩余数字进行按位与，然后添加一个固定值$x$。 基里尔希望他选择的集合的 GCD 严格大于这个蓝色表达式。 

任务不是简单地优化所有子集，而是确定是否存在任何有效的分割，如果存在则构造一个。 

这些约束已经表明枚举所有子集是不可能的。 即使对子集进行有限搜索也会呈指数级增长$n$， 尽管$n$上升到$4 \cdot 10^5$。 所有测试用例的总和约束迫使我们对每个用例进行线性或接近线性的处理。 

主要困难在于双方都依赖于互补子集，因此更改一个元素会以非局部方式影响 GCD 和 AND。 一种简单的方法可能会尝试修复红色集并直接计算这两个值，但这会导致$O(2^n)$可能性或至少$O(n^2)$扫描每个子集。 

当人们尝试贪婪的局部选择时，就会出现一种常见的失败情况。 例如，将最小的元素选择为红色以最大化 GCD 行为是具有误导性的：

 输入：```
n = 4, x = 0
a = [1, 2, 3, 6]
```选择小元素，例如$[1,2]$给出 GCD 1，但蓝色一侧 AND 仍然可以是 2 或 0，具体取决于选择，这使得比较不稳定。 关键问题是 GCD 仅依赖于仔细对齐的子集结构，而不仅仅依赖于大小。 

当最佳红色集非常小时（通常为 2）时，会出现另一个微妙的失败，而朴素方法假设较大的子集会提高 GCD，这是错误的。 

## 方法

 蛮力解释很简单：选择 2 到 2 之间的每个有效大小子集$n-2$，计算其 GCD，计算补 AND 加$x$，并进行比较。 这是正确的，因为它直接模拟了游戏规则。 然而，子集的数量是$\sum_{k=2}^{n-2} \binom{n}{k}$，这是指数级的。 即使每次评价都是$O(n)$，该解不可行。 

关键的结构观察是集合的 GCD 由整除性约束决定，而补集的 AND 由按位包含决定。 这两个操作在按除数和位模式进行过滤方面表现良好。 

我们不选择任意子集，而是翻转观点：固定一个候选值$g$为红色集的 GCD。 如果红色集合的 GCD 等于$g$，那么每个红色元素都必须能被整除$g$，并且该集合必须至少包含两个这样的元素。 问题是我们是否可以选择至少两个倍数$g$使得所有剩余元素产生足够小的 AND。 

当我们注意到即使蓝色集合中的一个元素在某个位置有零位时，AND 部分就会变得更容易，AND 会丢失该位。 这意味着 AND 主要由位模式的交集决定，因此删除仔细选择的子集可以显着减少它。 

关键的简化是，好的解决方案始终可以简化为为红色集选择恰好两个元素。 如果 GCD 存在有效的较大红色集$g$，那么在这些元素中我们可以选择两个 GCD 仍然为$g$，因为 GCD 是关联的，并且任何实现它的子集都包含见证对。 

这将问题减少到尝试配对，但仍然不是所有配对都可行$O(n^2)$。 最终的优化是按值分组并使用频率和除数结构，仅从数组域检查候选者。 

对于每个值$v$，我们将其视为潜在的 GCD 目标。 我们检查有多少个元素可以被整除$v$。 如果至少存在两个，我们可以形成一对红色。 然后我们计算除这两个元素之外的所有元素的 AND，这可以使用前缀/后缀位技巧或全局位计数来有效维护。 

这导致了一个迭代值最多的解决方案$4 \cdot 10^5$，累积整除计数并使用除数枚举在近线性总时间内验证条件。

 ## 算法演练

 1. 预先计算数组中每个值的频率。 这样可以快速推理出每个可能的 GCD 存在多少个候选者。 
2. 对于每个可能的值$g$从 1 到最大元素，计算有多少个数组元素可以被整除$g$。 这告诉我们是否可以选择至少两个可以形成 GCD 可整除的红色组的元素$g$。 这很重要的原因是任何有效的红色集合必须完全位于其 GCD 的倍数内。 
3. 如果少于两个元素可以被整除$g$，跳过它，因为我们甚至无法形成有效的红色集。 
4. 尝试使用两个元素来构造红色集合，这两个元素是$g$。 我们选择两个保留 GCD 条件的元素，这可以通过检查它们的实际 GCD 是否相等来确保$g$。 
5. 暂时删除这两个元素并计算剩余元素的按位与。 这是使用预先计算的全局 AND 或基于频率的位重建来完成的。 
6. 添加$x$对此 AND 结果进行比较$g$。 如果$g$严格来说，我们已经找到了一个获胜的配置。 
7. 将所选的红色对和所有剩余元素输出为蓝色。 

### 为什么它有效

 任何有效的红色集合都有明确定义的 GCD$g$。 该集合必须包含在其值可被整除的索引内$g$。 其中，GCD 的最小见证人始终是 GCD 已经存在的一对元素$g$，因为任何更大的集合都会减少到$g$必须包含生成它的一对。 这将搜索空间从子集减少到对，而不会丢失任何有效的解决方案。 一旦红色集被固定，蓝色集也被确定，并且比较变得确定性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXV = 400000

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    freq = [0] * (MAXV + 1)
    for v in a:
        freq[v] += 1

    # global bit counts for AND reconstruction
    bit_cnt = [0] * 20
    for v in a:
        for b in range(20):
            if v >> b & 1:
                bit_cnt[b] += 1

    def full_and(excluded):
        cnt = bit_cnt[:]
        for v in excluded:
            for b in range(20):
                if v >> b & 1:
                    cnt[b] -= 1
        res = 0
        m = n - len(excluded)
        for b in range(20):
            if cnt[b] == m:
                res |= (1 << b)
        return res

    for g in range(1, MAXV + 1):
        tot = 0
        for m in range(g, MAXV + 1, g):
            tot += freq[m]
        if tot < 2:
            continue

        found = []
        for v in range(g, MAXV + 1, g):
            if freq[v]:
                found.extend([v] * min(freq[v], 2))
                if len(found) >= 2:
                    break
        if len(found) < 2:
            continue

        a1, a2 = found[0], found[1]

        red_gcd = a1 if a1 == a2 else __import__("math").gcd(a1, a2)
        if red_gcd != g:
            continue

        blue = []
        removed = 0
        for v in a:
            if removed < 2 and v in (a1, a2):
                removed += 1
                continue
            blue.append(v)

        blue_and = full_and([a1, a2])
        if g > blue_and + x:
            print("YES")
            print(2, a1, a2)
            print(len(blue), *blue)
            return

    print("NO")

t = int(input())
for _ in range(t):
    solve()
```该实现首先构建频率和位统计数据，以便可以测试候选 GCD 值，而无需重复扫描数组。 辅助函数在使用位计数删除红色对后重建蓝色集的 AND，这避免了从头开始重新计算 AND。 

关键的实现微妙之处是确保正确排除两个元素。 由于存在重复项，因此删除是通过计算出现次数而不是基于索引的删除来处理的。 

## 工作示例

 考虑输入：```
n = 4, x = 1
a = [4, 3, 1, 8]
```我们测试可能的 GCD 候选者。 

| 克| 可整除计数 | 已选对 | 红色GCD | 蓝色 AND + x | 有效 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 4 | (4,3) | 1 | (1 & 8)+1 = 1 | 没有|
 | 2 | 2 | (4,8) | 4 | (3 & 1)+1 = 2 | 是的 |

 我们停在$g=2$， 自从$2 > 2$为 false，但略有不同的对可能满足条件，具体取决于 AND 结构。 该跟踪显示了候选过滤如何将搜索空间从所有子集减少到几个可分类别。 

现在考虑：```

a = [5, 10, 15, 20, 25]
```| 克| 可整除计数 | 已选对 | 红色GCD | 蓝色 AND + x | 有效 |

 整个数组可被 5 整除，因此任何对都适用于红色，蓝色 AND 折叠为 0，使得不等式很容易满足。 

这些例子表明，问题是由可分结构而不是排列驱动的。

 ## 边缘情况

 关键的边缘情况是所有元素都相同。 在这种情况下，任何有效的红色子集的 GCD 都等于该值，而蓝色 AND 保持相同的值，因此比较简化为检查是否$g > g + x$，这是不可能的，除非$x < 0$，所以答案总是“否”，除非构造改变子集大小。 

当只有两个元素可被候选 GCD 整除时，会出现另一种边缘情况。 该算法仍然有效，因为红色集必须完全由这两个元素组成，而正确性取决于验证它们的 GCD 是否与候选者匹配。 

最后一个微妙的情况是，在删除一对后，蓝色集合的 AND 变为零。 这使得不平等仅取决于是否$g > x$，这通常成为主要的获胜条件，并解释了实践中许多“是”的输出。
