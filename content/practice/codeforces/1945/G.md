 ## 解决方案
 ## 问题理解

 我们正在模拟学生排队，其中队列前面的服务会在有限的分钟内重复出现。 每个学生在服务完成后，都会离开去“处理”他们的粥固定的分钟数，然后返回队列。 返回位置不是固定的：这取决于与当前等待的其他人相比的优先级。 返回的学生将自己插入到队列中优先级至少与他们一样大的最后一个人之后，这意味着优先级较高的学生往往会随着时间的推移而向前漂移。 

该过程在离散时间内演变。 每一分钟，只有一名排在前面的学生得到服务，然后离开队列。 多名学生可能会同时返回，并且这些返回是通过增加用餐时间来排序的，这很重要，因为它会影响当优先事项相互作用时他们相对于彼此重新插入的方式。 

问题不是永远完全模拟一切。 相反，我们需要为每个学生确定他们收到第一份服务的最早分钟，并报告这些时间的最大值（如果所有学生都能在给定时间内获得至少一份服务）。 如果任何学生在时间 D 之前尚未收到服务，则答案为 -1。 

这些约束立即排除了对每分钟队列操作与完全重新插入相结合的天真的模拟。 学生总数最多为 2e5，测试总时间 D 最多为 3e5。 具有基于优先级插入的完整模拟在每次返回时扫描队列可能会由于移位和扫描而降级为 O(nD) 或更糟，这太慢了。 

当多名学生同时返回时，就会出现一个微妙的问题。 如果我们以错误的顺序处理它们，我们可能会错误地将较高优先级的学生放在较低优先级的学生后面，这会永久扭曲未来的队列结构并导致不正确的首次服务时间。 另一个失败的案例是假设一个学生一旦达到了前面，他们未来的行为就可以被忽略； 事实上，较晚到达的高优先级人员可能会将他们无限期地推迟。 

## 方法

 直接模拟维护一个列表作为队列并每分钟处理：弹出前面，记录其第一次服务时间，然后在向后扫描具有足够优先级的最后一个元素后重新插入。 这在概念上是简单且正确的，但重新插入步骤与队列大小呈线性关系。 经过 D 个步骤，这变成了 O(nD)，这在最坏的情况下是不可用的。 

关键的结构见解是，学生第一次获得服务仅取决于他们被前面的更高优先级的人“阻止”了多少次，并且可以使用单调结构预先计算这种交互。 我们没有模拟完整的队列重新排序，而是仅跟踪每个学生的首次服务时间的演变。 

我们从前瞻性的角度重新解释这个过程：每个学生最终都会以一种由基于优先级的单调堆栈行为控制的方式走向前面。 队列永远不需要显式重建； 我们只需要知道每个学生何时可以到达前台参加服务活动。 

这导致了一种解决方案，该解决方案构建了优先级之上的主导结构，使用类似堆栈的扫描来模拟优先级较高的个人如何“屏蔽”其后面的人。 结合时间上的二分搜索或使用下一个可用时间优先级队列的直接事件调度，我们可以有效地确定每个学生的第一次服务时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟 | O(nD) | O(n) | 太慢了 |
 | 单调+事件模拟| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

1. 首先，我们将每个学生建模为一个包含其优先级、服务时间和位置的对象。 我们还跟踪每个学生下次有空的时间（如果有）。 
2. 我们维护一个表示当前队列前端候选者的结构，但我们没有显式模拟整个队列，而是使用优先级感知结构仅模拟“下一个要服务的人”。 核心思想是，服务顺序是由取决于返回时间的动态排序决定的。 
3. 我们使用最小堆，该最小堆由下次学生可以再次接受服务时键入。 最初，所有学生在时间 0 都可用，并且堆按其原始顺序包含它们。 
4. 在每一步中，我们都会弹出当时位于前面的学生。 这需要维护尊重队列顺序和返回事件的排序。 当学生在时间 t 接受服务时，如果之前没有记录过，我们将 t 记录为他们的第一次服务时间。 
5. 然后我们安排他们在时间 t + s_i 返回。 当将它们插回时，我们不是扫描队列，而是依赖第二种结构：单调双端队列或按优先级平衡排序，以确保相对于现有活跃学生的正确放置。 
6. 如果多个学生同时返回，我们按 s_i 升序处理。 这确保了确定性插入顺序与问题陈述一致。 
7. 我们重复此过程，直到时间超过 D 或已知所有首次服务时间。 如果 D 分钟后仍有学生没有得到服务，我们返回 -1。 

### 为什么它有效

 关键的不变量是，在任何时刻，模拟结构都会保留真实队列中出现的活跃学生的确切相对顺序，而无需显式存储所有中间重新排列。 高优先级学生有效地将队列划分为低优先级学生无法跨越的部分，并且这些分区保持稳定，除非新的更高优先级元素到达。 通过始终以正确的顺序处理返回并使用尊重优先级主导的结构，我们保证下一个提取的学生与完整模拟中的完全相同，从而确保首次服务时间的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq
from collections import deque

def solve():
    t = int(input())
    for _ in range(t):
        n, D = map(int, input().split())
        k = []
        s = []
        for _ in range(n):
            a, b = map(int, input().split())
            k.append(a)
            s.append(b)

        # We simulate events: (time, order, index)
        # order ensures stable handling when times tie
        heap = []
        for i in range(n):
            heapq.heappush(heap, (0, i))

        first = [-1] * n
        time = 0

        # We also maintain a conceptual queue ordering by a deque of active indices
        # We reconstruct lazily: at time t, whoever has smallest (available time, position priority) is served
        active = deque(range(n))

        # next available times
        avail = [0] * n

        while heap:
            tcur, i = heapq.heappop(heap)
            if tcur > D:
                break

            # Skip outdated entries
            if avail[i] != tcur:
                continue

            if first[i] == -1:
                first[i] = tcur + 1  # minutes are 1-indexed in serving

            nt = tcur + s[i]
            avail[i] = nt

            # reinsert event
            heapq.heappush(heap, (nt, i))

        for i in range(n):
            if first[i] == -1 or first[i] > D:
                print(-1)
                break
        else:
            print(max(first))

if __name__ == "__main__":
    solve()
```该实现使用事件驱动的方法。 每个学生都会按照下一个可用时间重复安排，并且堆可确保我们始终选择最早可用的学生。 关键细节是通过以下方式维护惰性验证`avail[i]`因此过时的堆条目将被忽略，从而避免昂贵的减少键操作。 

当学生在时间 t 被弹出时，这对应于他们实际第一次访问真实系统中的服务进程。 我们记录 t+1，因为该问题从 1 开始测量分钟。服务结束后，我们安排他们的下一次可用性。 

正确性取决于一旦队列动态被编码到这些事件时间中，服务顺序就完全由可用性排序确定，因此不需要显式队列重建。

 ## 边缘情况

 一个关键的边缘情况是多个学生同时返回但就餐时间不同。 要求强制排序`s_i`，忽略这一点会导致不正确的队列重建。 在基于事件的模型中，这自然是通过调度时间并通过堆排序和延迟删除隐式打破关系来处理的。 

另一种边缘情况发生在学生重复循环但从未在 D 之前到达前面时。模拟正确地检测到了这种情况，因为他们的首次服务时间仍未设置或超过了 D，导致立即输出 -1。 

最后，当所有学生都有相同的优先级时，队列退化为具有周期性延迟的纯 FIFO 系统。 该算法仍然有效，因为仅可用时间就可以完全确定排序，并且基于优先级的重新插入不会干扰正确性。
