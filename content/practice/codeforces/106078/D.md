 ## 解决方案
 ## 问题理解

 我们得到了一系列排成一排的石块。 从这一行，我们可以选择一个连续的段。 一旦选择了一个细分市场，我们就会根据其内部价值的分布来评估其“享受”。 

对于任何选定的部分，我们将相同的质量分组在一起。 如果一个质量值`m`出现`f`次在该段内，它贡献`m * f`至总分。 由于每个出现在其自己的组中只计算一次，因此该表达式简化为对每个元素求和，但有一个约束：我们不会对所有子数组进行优化，我们将自己限制为最多包含的段`k`独特的价值观。 

所以任务简化为找到一个最多有`k`最大化其元素之和的不同数字。 

输入是整数列表，我们必须在不同计数约束下输出所有有效子数组的最大可能总和。 

约束条件`n ≤ 10^5`立即排除任何枚举所有子数组的二次方法。 开始和结束的双循环将大致生成`n^2 / 2`段，其周围`5 * 10^9`最坏情况下的操作，远远超出1-2秒的限制。 这推动我们走向线性或近线性滑动窗口式的解决方案。 

一个微妙的点是，由于“频率乘以值”的措辞，评分函数最初可能看起来比总和更复杂。 一种天真的解释可能会建议跟踪每个窗口内的频率并从头开始重新计算贡献，但这会导致每个窗口扩展都重复工作。 

打破朴素推理的边缘情况主要与独特的约束有关。 

像这样的案例`1 1 1 1`和`k = 1`很简单：整个数组都是有效的并且应该被选择。 如果粗心的实现错误地将重复项视为增加的不同计数，则可能仍会尝试不必要地缩小窗口。 

一个更有趣的案例是`1 2 3 1 2`和`k = 2`。 最佳窗口不一定是最长的前缀或后缀。 如果算法贪婪地扩展而没有仔细删除过时的元素，则最终可能会得到三个不同的值，并根据簿记的方式错误地接受或拒绝窗口。 

## 方法

 蛮力策略是考虑每个子数组`[l, r]`，计算其中不同值的数量，如果最多`k`，计算其总和并更新答案。 维护每个窗口的频率图将允许重新计算不同的计数，但重新计算总和或重置每个窗口的频率结构`l`根据实现风格，会导致三次或二次行为。 即使增量更新，迭代所有`l`仍然有力量`O(n^2)`窗口扩展，这对于`n = 10^5`。 

关键的观察是总和和不同计数在滑动窗口下表现良好。 当我们扩展右边界时，我们可以在常数时间内更新总和和频率。 当不同值的数量超过`k`，我们可以将左边界向前移动，直到约束恢复。 这将问题转化为维护在每个位置结束的最佳有效窗口。 

暴力方法之所以有效，是因为它明确地检查了所有候选者，但它失败了，因为它重复地重新计算重叠信息。 滑动窗口方法通过确保每个元素最多进入和离开窗口一次来消除这种冗余。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 滑动窗| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们维护窗口中当前值的频率表，以及当前总和和不同元素的数量。 

1.初始化两个指针`l = 0`,`r = 0`，连同`current_sum = 0`,`distinct = 0`，和一个空的频率图。 我们正在准备一个永远有效的窗口。 
2. 移动`r`从左到右穿过阵列。 每次我们包括`a[r]`，我们将其添加到总和中并更新其频率。 如果该值第一次出现在窗口中，我们将增加非重复计数器。 此步骤确保我们始终知道当前窗口的确切贡献，而无需重新计算。 
3.插入后`a[r]`，检查窗口是否违反约束`distinct > k`。 如果是这样，我们通过移动从左侧缩小窗口`l`向前，从总和中删除元素并更新频率。 每当频率下降到零时，我们就会减少不同的计数器。 我们继续缩小，直到约束恢复。 这确保了窗口在评估之前始终有效。 
4. 一旦窗口有效，我们将更新答案`current_sum`。 这是正确的，因为对于每个右端点`r`，我们正在考虑满足约束的最佳可能左边界。 
5. 继续此过程直到`r`到达数组末尾。 

### 为什么它有效

 在任意固定位置`r`，算法保持最小可能的左边界`l`这样子数组`[l, r]`最多包含`k`独特的价值观。 任何其他有效的子数组结束于`r`必须从此处或右侧开始`l`，这只会减少总和，因为所有数字都是非负数。 因此，算法维护的窗口是该端点的最佳候选，并且在所有端点上取最大值涵盖了所有可能性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    freq = {}
    l = 0
    distinct = 0
    current_sum = 0
    best = 0

    for r in range(n):
        x = a[r]
        current_sum += x

        if x not in freq or freq[x] == 0:
            freq[x] = 1
            distinct += 1
        else:
            freq[x] += 1

        while distinct > k:
            y = a[l]
            freq[y] -= 1
            current_sum -= y
            if freq[y] == 0:
                distinct -= 1
            l += 1

        best = max(best, current_sum)

    print(best)

if __name__ == "__main__":
    solve()
```其实现直接遵循滑动窗口结构。 频率字典跟踪每个值出现的次数，并且`distinct`counter 避免重复重新计算字典大小。 关键的微妙之处在于更新`current_sum`扩展和缩小窗口时对称，否则答案将偏离实际的子数组和。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个元素最多进入和离开窗口一次，因此所有指针和频率更新都是线性的 |
 | 空间| O(n) | 频率映射在数组中为每个不同值最多存储一个条目 |

 线性复杂度完全符合以下约束：`n ≤ 10^5`，内存使用量受不同值的数量限制，最多也是`n`。 因此，该解决方案满足了这两个限制，并有剩余空间。

 ## 边缘情况

 当所有元素都相同时，频率图会增长，但`distinct`永远不会超过 1，因此窗口始终扩展至全长。 该算法正确地保持单个更新路径并且永远不会触发收缩。 

什么时候`k`等于`n`，约束永远不会激活。 窗口变成整个数组，算法退化为计算前缀和，同时保持正确性保证，而不需要向左移动任何指针。 

当价值观发生剧烈变化并且`k = 1`，每个新元素都会立即收缩。 左指针有效地跟踪右指针，并且窗口大小永远不会超过 1。这证实了收缩逻辑即使在最坏情况的振荡输入中也能正确恢复有效性。
