 ## 解决方案
 ## 问题理解

 我们正在管理一小批在火星和地球之间旅行的牛奶罐。 宇宙飞船旅行要么从火星到地球，要么从地球到火星。 当一个罐子在火星到地球的旅行中到达地球时，它会立即被装满。 为了带回牛奶，我们必须将装满的罐子分配给稍后的地球到火星之旅。 每艘飞船最多可以运载我们一个罐子。 

重要的是约翰尼一开始只拥有两个空罐子。 正在移动的水壶不可用。 成功返回火星后，水壶又空了，可以重复使用。 任务是最大限度地向火星运送多少满罐牛奶。 

输入描述了多达 100000 次宇宙飞船旅行。 每个行程都有开始时间、结束时间和方向。 由于行程数量很大，任何尝试每对可能的行程的方法都太慢。 最多有大约 10^10 个可能的对，这不能满足一秒的样式限制。 我们需要处理接近线性时间的行程。 

棘手的情况是由于水壶是一种资源，而不仅仅是一个选定的间隔这一事实引起的。 一次看似有用的旅行可能会占用很长时间并妨碍更好的顺序。 

例如，考虑：```
3
0 100 0
1 2 0
3 4 1
```答案是`1`。 

粗心的解决方案可能会认为两次地球旅行总是最好的。 然而，只有一次火星返回可用。 长途旅行无法在时间 4 之前返回，因此只有短途旅行可以产奶。 

另一个案例：```
4
0 5 0
1 2 0
3 4 1
6 7 1
```答案是`1`。 

如果我们只计算兼容的旅行对，我们可能会认为两次地球旅行都是有用的。 他们不是。 短暂的地球之旅和第一次火星之旅可以完成一个周期。 第二次地球之旅还要等到时间5才填满，所以错过了早期的火星之旅。 

该解决方案必须按时间顺序做出决策并记住可用水壶的数量。 

## 方法

 直接方法将尝试将每次火星到地球旅行与后来的每次地球到火星旅行相匹配。 对于每个可能的对，我们可以检查第一次旅行是否在第二次旅行开始之前完成，以及可用的罐子是否允许这种选择。 这是正确的，因为每个可能的导入都由这样的一对来表示。 然而，对于 100000 次行程，检查所有对需要大约 10^10 次操作，这远远超出了可能的范围。 

关键的观察是唯一有限的资源是水罐的数量。 我们永远不需要知道哪个特定的水壶是免费的，只需要知道有多少是免费的。 每个事件都会改变这个计数。 当火星到地球之旅开始时，一个空罐子可能会离开。 当它到达地球时，它变成一个装满水的罐子等待返回。 当地球到火星的旅程开始时，等待装满的罐子就可以离开。 当它到达火星时，罐子又变空了。 

这将问题变成了对所有行程端点的扫描。 贪婪的选择是总是在最早可能的事件中使用任何可用的罐子。 提前使用空水壶不会有什么坏处，因为如果我们跳过较早的行程，水壶就会一直闲置直到稍后。 较早开始可以为壶提供至少同样多的时间来完成一个循环。 

同样，当有回程时，立即发送装满的水壶是最佳选择，因为它只会更快地增加空闲水壶的数量。 

该实现保留了两个计数器：火星上空罐子的数量和地球上等待装满的罐子的数量。 按时间顺序处理事件足以模拟最佳调度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 最佳扫描 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 为每次宇宙飞船旅行创建两个事件。 开始事件代表飞船离开的时刻，结束事件代表飞船到达的时刻。 我们两者都需要，因为壶在这两种情况下都会改变状态。 
2. 按时间对所有事件进行排序。 每个时间值都是唯一的，因此更改顺序不会有歧义。 
3. 维持火星上空罐子的数量。 最初该值为 2，因为约翰尼拥有两个空罐子。 
4. 维持当前在地球上等待的装满水的罐子的数量。 最初为 0，因为尚未运输牛奶。 
5. 当火星到地球出发时，如果有空罐子，请使用空罐子。 罐子离开火星，因此空罐子的数量减少。 
6. 当同一次旅行到达地球时，罐子现在已经装满并等待返程。 增加装满水的罐子的数量。 
7. 当地球到火星出发时，发送一个装满水的水壶（如果有的话）。 减少装满水的罐子的数量。 
8、回程抵达火星时，牛奶已顺利送达。 增加空罐子的数量并增加答案。 

为什么它有效：

 不变的是，在每个处理的事件之后，计数器准确地代表了截至该时间的所有决策之后的最佳可能状态。 提前开始火星到地球的旅行永远不会减少未来的可能性，因为它只会将一个可用的罐子移动到最终可能产生牛奶的状态。 尽快归还装满的水壶只会提前释放资源。 由于每个选择都是在尽可能早的时刻做出的，因此未来的序列不可能比这种贪婪的模拟拥有更多的可用资源。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    events = []

    for _ in range(n):
        l, r, t = map(int, input().split())
        if t == 0:
            events.append((l, 0, 0))
            events.append((r, 1, 0))
        else:
            events.append((l, 0, 1))
            events.append((r, 1, 1))

    events.sort()

    empty = 2
    filled = 0
    ans = 0

    for _, kind, direction in events:
        if kind == 0:
            if direction == 0:
                if empty > 0:
                    empty -= 1
            else:
                if filled > 0:
                    filled -= 1
        else:
            if direction == 0:
                filled += 1
            else:
                empty += 1
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该代码将每个行程端点存储为一个事件。 第三个字段区分原始行程的方向，而第二个字段区分出发和到达。 

扫描变量直接代表真实情况。`empty`计算可以放置在火星到地球飞船上的水壶。`filled`计算已到达地球并准备返回的罐子。 当返回到达时，答案会增加，因为那正是牛奶到达火星的时刻。 

操作的顺序是通过对所有事件进行排序来处理的。 因为所有时间都是不同的，所以赛事之间不存在决胜问题。 计数器仅在相应的物理动作发生后才会更新，从而避免行程边界附近出现相差一的错误。

 ## 边缘情况

 对于长途地球旅行阻碍短途旅行的情况：```
3
0 100 0
1 2 0
3 4 1
```扫描在时间 0 开始第一次行程，在时间 1 开始第二次行程，因为两个罐子都是空闲的。 短途旅行在时间 2 填满并在时间 4 返回，从而产生一次成功的导入。 长途旅行只在时间100时填充，在返回机会过去之后，所以最终答案是`1`。 

对于必须重复使用相同水壶的情况：```
4
0 2 0
4 6 0
1 3 1
5 7 1
```第一个罐循环在时间 3 完成。释放的罐再次被计为空，可用于第二个循环。 答案就变成了`2`，表明该算法跟踪水壶的生命周期，而不是将它们视为一次性对象。
