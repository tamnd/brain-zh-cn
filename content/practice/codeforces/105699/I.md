 ## 解决方案
 ## 问题理解

 每轮游戏都会呈现您当前资本的状态以及法官选择的整数。 该整数是从 1 到您当前资金的范围内均匀提取的，因此较大的余额会立即增加该轮可能结果的范围。 

看到该值后，您可以选择是否参与该回合或跳过该回合。 如果你参与，这一轮的行为就像一场对称赌博：以相同的概率，你要么输掉所选择的金额，要么获得两倍的金额。 跳过只是进入下一轮而不改变你的钱，但未来随机选择的顺序仍然取决于你当前的余额。 

游戏进行固定轮数，除非您达到严格高于 10000 的非常大的目标余额，或者您的资金变为零。 这种相互作用使情况变得更加微妙，因为每个决定都会改变所有未来轮次的分配，因为可能值的范围取决于当前资本。 

约束 T 很小并且固定为 1000，这排除了对所有可能的结果序列探索决策树的任何尝试。 即使没有分支，以状态相关的随机性精确模拟 1000 轮以上的概率也是不可行的。 关键的困难在于该过程是交互式的和自适应的，因此货币状态上的朴素概率动态规划会由于连续的状态爆炸而失败。 

一个常见的陷阱是试图用期望值逐轮推理。 对于固定 b，玩一轮的预期收益为正，因为结果为 +b 和 -b 的概率相同，给出预期变化 +b/2。 然而，这忽略了 b 和当前资金之间的依赖关系，更重要的是忽略了方差：重复游戏可以让你归零并提前终止该过程。 另一个错误是过早跳过，然后玩得太激进，这可能会导致您达到高方差状态，由于较大的采样 b 值，更有可能失败。 

## 方法

 暴力解释将尝试模拟所有可能的游戏结果并跳过 1000 轮的决策。 即使我们在玩游戏时只根据抛硬币的结果进行分支，每一轮都会引入一个分支因子 2（用于玩）加上 1（用于状态不变的跳过），同时还会改变未来随机值的分布。 这很快就会在 T 中呈指数增长，甚至通过合并相同的货币值来截断状态也无济于事，因为货币是一个连续整数，直到可能非常大的值，并且每次转换都会改变所有未来轮次的采样空间。 

关键的结构观察是，游戏的设计使得任何合理的策略都不需要以细粒度的方式适应中间随机性。 这种交互在分配上是对抗性的，但在隐藏信息上不是对抗性的：法官的选择b对于当前的资金总是一致的，所以唯一有意义的控制变量是当当前状态足够安全时我们是否参与。 

一个关键的简化是注意到每轮赌博相对于当前资本具有正漂移和有限的下行空间。 如果我们远离失败边界（金钱 0），那么玩游戏的预期总是比跳绳更好，而跳绳只会减少方差风险，而不会提高预期增长。 由于获胜条件是基于阈值的，因此最佳策略是只要我们不面临立即崩溃的风险，就始终利用积极的期望。

这将决策问题简化为确定性策略：在金钱为正数时始终进行游戏。 然后，交互变成仅由重复的对称乘加更新驱动的单一随机过程，并且交互方面从决策逻辑中消失。 

那么实现就很简单了：始终输出 PLAY 直到系统结束游戏。

 ## 算法演练

 我们按顺序处理回合，对法官的每个询问做出反应。 

1.读取当前回合状态，由当前货币m和采样值b组成。 仅当我们选择玩时，b 值才重要。 
2. 决定只要游戏尚未结束，就始终以 PLAY 进行响应。 原因是，玩游戏会产生积极的预期收益，而跳过游戏只会减少暴露程度，而不会改善预期漂移。 
3.立即输出决策并flush，因为交互需要严格同步。 
4. 每次响应后，等待下一个状态。 如果裁判发送胜利或失败，则立即终止。 

### 为什么它有效

 每次游戏的过程都有预期的变化+b/2，并且b始终是非负的并且受当前资金的限制。 跳过不会以补偿丢失的正漂移的方式改变未来 b 值的分布。 在超过 1000 个回合中，持续采取积极的漂移机会在任何选择性避免这些机会的策略中占主导地位，因为没有外部对手根据超出统一采样规则的决策来调整结果。 唯一吸收失败的状态是达到零，并且更新的结构确保与玩游戏所增加的预期收益相比，避免玩游戏不会降低达到零的概率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    T = input().strip()
    if not T:
        return
    T = int(T)

    for _ in range(T):
        line = input().strip()
        if not line:
            return

        if line == "WIN" or line == "LOSE":
            return

        # line format: "ROUND m b"
        print("PLAY", flush=True)

if __name__ == "__main__":
    main()
```该解决方案只需通过打印 PLAY 对每一轮提示做出反应。 唯一的微妙之处是处理提前终止信号，该信号必须立即停止执行以避免交互不同步。 由于法官期望实时响应，因此每次输出后必须进行刷新。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    T = sys.stdin.readline().strip()
    if not T:
        return ""
    T = int(T)

    for _ in range(T):
        line = sys.stdin.readline().strip()
        if not line:
            break
        if line in ("WIN", "LOSE"):
            break
        print("PLAY")

    return out.getvalue().strip()

 ## 边缘情况

 一种边缘情况是在做出任何决定之前立即终止。 如果 T 之后的第一行是 WIN 或 LOSE，则程序不得尝试打印任何内容。 该解决方案通过在发出输出之前检查传入线路来处理此问题。 

另一种情况是部分输入，即判定在获胜条件后提前结束。 循环在看到 WIN 后立即退出，防止额外的打印导致协议不同步。 

最后一种情况是由于交互缓冲而出现空行或格式错误的行。 该实现通过在发生空读取时中断来防止这种情况，确保它永远不会阻塞或产生未定义的输出。
