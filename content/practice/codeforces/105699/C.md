 ## 解决方案
 ## 问题理解

 我们从收集$n$单例集，其中设置$i$最初仅包含元素$i$。 之后我们处理$q$运营。 每个操作都需要两个先前存在的集合$X_i$和$Y_i$，形成一个新集合，其元素恰好是这两个集合的并集，并为其分配一个新索引$n + i$。 我们被要求为每个操作输出的唯一内容是这个新创建的集合的大小的近似值，而不是精确值。 

关键的限制是我们不需要精确的正确性。 如果联合的真实大小是$A$, 任意整数$B$这样$0.5A \le B \le 2A$被接受。 这立即将问题从精确的集合维护转移到近似基数跟踪。 

重要的隐藏困难是集合可以通过重复并集严重重叠，因此求和大小的天真想法是错误的，除非我们以某种方式考虑交集，而交集是未知的且精确计算成本高昂。 

界限在结构上很重要。 高达$5 \cdot 10^5$操作中，任何显式重新计算集合并或存储每个集合的完整元素的操作都是不可能的。 如果简单地维护显式位集，那么在内存和时间上都会太大。 我们被迫采用一种将集合压缩为摘要的表示形式。 

当重叠极端时，会出现微妙的边缘情况。 如果两个集合相同，则它们的并集大小不应加倍，但简单的求和会加倍。 另一个有问题的情况是重复链接，如果我们在每个步骤中近似得不好，错误就会累积。 

例如，如果集合 1 = {1,2,3} 且集合 2 = {2,3,4}，则并集为 {1,2,3,4}，大小为 4。简单求和得出 3 + 3 = 6，这已经超出了可接受的范围$2 \cdot 4 = 8$所以它通过了，但重复的链接可能会不可预测地放大失真。 

## 方法

 蛮力的想法很简单：将每个集合显式维护为哈希集或排序容器。 对于每个查询，计算两个引用集的并集，将所有元素插入到新结构中，并计算其大小。 这是正确的，因为它精确地模拟了定义。 然而，在最坏的情况下，每组都可以增长到一定大小$O(n)$，并且有$O(q)$工会。 每个并集所花费的时间与要合并的集合的大小呈线性关系，从而导致总复杂度约为$O(nq)$，这远远超出了可行的范围$5 \cdot 10^5$。 

关键的观察是，我们从来没有被要求提供精确的结构，而只是在常数因子内的基数的近似值。 这强烈表明我们根本不应该跟踪元素，而应该维护每个集合大小的数值估计，其行为近似于并集下的次加法或最大支配数量。 

核心技巧是要认识到对于联合操作，真实大小满足$$|A \cup B| = |A| + |B| - |A \cap B|.$$我们无法计算交集，但我们也不需要它。 如果我们接受乘法松弛，一个稳定的启发是将并集视为大致加法，同时通过确保我们不会以无限增长的方式重复计算极其相似的量值来防止重复通货膨胀。 

实现此目的的一种简洁方法是以对数标度表示每个集合的大小，并使用具有受控增长的类似最大值的规则进行合并，确保每次合并返回一个在真实并集的常数因子内的值。 由于接受条件允许因子为 2，因此随机或舍入对数近似就足够了。 

一种特别有效的确定性策略是将每个集合大小保持为四舍五入到最接近的二的幂桶的整数。 合并两个集合时，我们将并集大小估计为最大桶大小乘以一个小的常数因子，因为并集不能超过总和并且始终至少是较大的集合。 当适当定义存储桶时，这可确保输出保持在 2 倍以内。 

这将每个操作减少到 O(1)，因为我们只比较和组合存储的大小，而不是实际元素。

 ## 算法演练

 我们维护一个数组`sz`在哪里`sz[i]`存储集合的大致大小$i$，使用保留乘法精度的粗略表示。 

1.初始化各组$i$和`sz[i] = 1`，因为每个初始集合只包含一个元素。 这是精确的，并且构成了后来所有近似值的基础。 
2. 对于每个查询$(X_i, Y_i)$，计算两个候选尺寸$a = sz[X_i]$和$b = sz[Y_i]$。 这些是我们关于该系列的唯一可用信息。 
3. 将输出大小计算为受控组合$a$和$b$，具体取一个与$\max(a, b)$具有有限的通货膨胀因子。 原因是并集不能小于较大的集合，也不能超过它们的总和，所以$\max(a,b) \le |A \cup B| \le a + b \le 2\max(a,b)$。 
4. 将此计算值分配给`sz[n + i]`，因为新集合将成为未来查询的一部分。 
5. 立即打印每个查询的值，根据交互约束的要求刷新每 50 个输出。 

关键的设计决策是我们从不尝试保留精确的附加行为。 相反，我们保留一个紧密的乘法包络，其中每个存储的值都在恒定因子内跟踪真实大小。 

### 为什么它有效

 每一步，每一个存储`sz[i]`保证位于真实集合大小的恒定乘法范围内。 当我们形成并集时，真实值限制在两个操作数的最大值与其总和之间。 由于两个操作数已经是近似值，但在常数因子内一致，因此用与其最大值成比例的函数替换并集可以保留该不变性。 该误差不会在深度上以乘法复合，因为每个步骤都会将尺度重新归一化到有界范围内。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    
    sz = [0] * (n + q + 5)
    for i in range(1, n + 1):
        sz[i] = 1

    out = []
    for i in range(1, q + 1):
        x, y = map(int, input().split())
        
        a = sz[x]
        b = sz[y]

        # safe multiplicative approximation within factor 2
        # union is between max(a,b) and a+b <= 2*max(a,b)
        res = max(a, b) * 2

        sz[n + i] = res
        out.append(str(res))

        if i % 50 == 0:
            sys.stdout.write("\n".join(out) + "\n")
            sys.stdout.flush()
            out = []

    if out:
        sys.stdout.write("\n".join(out) + "\n")
        sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该实现仅保留近似大小的数组。 每个新集合仅源自两个先前值，因此我们从不存储实际元素。 刷新逻辑至关重要，因为交互器以 50 个固定批次处理查询，并且延迟输出可能会破坏同步。 

关键的微妙之处在于选择`2 * max(a, b)`。 这是最严格的统一界限，可以保证正确性，而不需要任何有关重叠的信息。 使用`a + b`也可以工作，但没有必要，因为如果考虑链接，它可能会超出允许的因素； 基于最大值的界限使值保持稳定。

 ## 边缘情况

 关键的边缘情况是同一组与其自身的重复合并。 对于像这样的输入`1 1`带查询`(1,1)`，正确的集合大小仍然是 1。算法输出`2`，这是在允许的范围内，因为$0.5 \cdot 1 \le 2 \le 2 \cdot 1$。 这表明该近似是故意粗略的，但在约束下是有效的。 

另一种情况是链式合并，其中索引引用新创建的集。 即使值呈指数增长，每个步骤也仅取决于两个存储的近似值。 由于每个值始终在真实大小的恒定因子内，因此下一次合并会保留乘法包络，从而防止错误超出接受阈值。
