 ## 解决方案
 ## 问题理解

 我们得到一个隐藏的二进制字符串集合，每个字符串的长度固定为 50。这些字符串有 n 个，但它们不会直接显示。 相反，我们只能通过查询来与它们交互，该查询比较两个位置 i 和 j 并返回相应字符串之间的汉明距离，这意味着它们之间有多少位位置不同。 

数据的结构很重要。 最初，n−1 个字符串是独立且均匀地随机生成的。 然后，其中一个字符串被复制一次，并且对所得的 n 个字符串的多重集进行打乱。 任务是识别与相同字符串对应的任何一对索引。 交互限制为 25,000 次查询，n 最多可达 1000。 

每个查询都是昂贵的，因为它是提取信息的唯一方法。 由于汉明距离是对称且确定性的，因此交互定义了一个完整的加权图，其中顶点是索引，边权重是未知 50 位字符串之间的距离。 目标是检测重复的顶点，这些顶点对应于相同的字符串，因此距离为零。 

这些约束意味着任何解决方案都应该以大约 O(n log n) 或 O(n^2) 的速度运行，并且查询中的常数因子很小。 简单的全对比较需要大约 n^2 / 2 次查询，当 n = 1000 时，最多约为 500,000 次，远高于 25,000 次的限制。 这立即迫使我们大幅减少比较次数。 

一个微妙的方面是字符串是随机的。 这不是化妆品。 这意味着不同的字符串在汉明距离上极不可能接近，并且不同字符串之间的碰撞几乎总是在 0-50 范围内相距很远。 这种概率分离允许基于采样位或部分签名的积极修剪策略。 

朴素推理的主要失败情况是假设我们可以直接通过精确距离相等进行聚类或使用全距离向量进行排序。 计算完整距离向量的成本太高，甚至存储它们也会超出查询预算。 

## 方法

 蛮力的想法很简单。 我们比较每对索引 (i, j)，询问它们的汉明距离，并寻找零结果。 由于重复对的距离必须为零，这保证了正确性。 

问题是成本。 有 n(n − 1) / 2 对，每对都需要一个查询。 对于 n = 1000，这大约是 500,000 次查询，远远超出了 25,000 次的限制。 因此，虽然暴力破解在概念上简单且正确，但它纯粹因为查询复杂性而失败。 

为了减少查询，我们利用只有一个字符串重复的事实。 这意味着只有一个等价类的大小为 2，而所有其他等价类的大小为 1。 我们不是比较所有内容，而是尝试识别可能包含重复项的小候选组。 

一个关键的观察结果是，如果两个字符串相等，则在与任何第三个字符串的所有汉明距离比较下，它们都无法区分。 这意味着对于任何 k，只要 i 和 j 重复，d(i, k) 就等于 d(j, k)。 因此，可以通过比较距离配置文件来检测重复项，但完整的配置文件成本太高。 

我们以不同的方式利用随机性。 由于字符串是均匀随机的，因此每个位位置的行为就像一个独立的随机特征。 我们可以使用基于枢轴的消除策略逐步过滤候选者。 我们维护一个候选索引，假设它代表重复的字符串之一，然后将所有其他索引与其进行比较。 每当我们找到另一个距离为零的索引时，我们就完成了。 否则，我们通过将匹配相同距离结构的候选者分组来消除不一致的候选者，并逐渐缩小范围。

更有效的框架是选择任意根并计算到它的距离。 在所有节点中，至少一个副本与另一个副本共享相同的到根距离结构。 通过使用随机主元和按距离分区迭代地细化候选集，我们确保重复对保留在同一个桶中，而预期桶大小由于随机性而快速缩小。 

这导致预期的查询次数为 O(n log n)，完全在限制范围内。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) 查询 | O(1) | O(1) | 太慢了|
 | 汉明距离上的枢轴分区 | O(n log n) 次查询（预期） | O(n) | 已接受 |

 ## 算法演练

 1. 选取任意一个指标作为初始候选代表。 这可以作为比较所有其他字符串的参考点。 
2. 查询候选索引到其他所有索引的汉明距离。 这会产生相对于候选人的距离签名。 
3. 根据返回的距离值将所有索引分组。 每个组包含索引，其字符串与候选者的汉明距离相同。 
4. 确定人数至少为两人的小组。 由于只有一个字符串是重复的，因此只有一组可以包含同一字符串的两个副本。 在随机性下，任何其他大小大于 1 的组的可能性极小，并且可以在预期中安全地忽略。 
5. 将注意力集中在候选人所在的群体上。 如果多个组的大小 ≥ 2，则选择任意一个并进一步细化。 
6. 通过从其中选择一个新的枢轴并仅在该组内重新计算距离，在所选组内重复该过程。 这逐渐缩小了搜索空间。 
7. 继续，直到只剩下两个索引。 它们必须对应于相同的字符串，并且它们之间的单个查询将返回距离零，从而结束交互。 

每次迭代的关键思想是枢轴引起的分区保留重复对。 如果两个索引相同，则它们将始终落入相对于任何枢轴的相同距离桶中，因此它们在细化过程中永远不会分离。 同时，随机的不相关字符串极不可能一致地匹配距离模式，因此它们很快就会分开。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())

alive = list(range(1, n + 1))

def query(i, j):
    print(i, j, flush=True)
    return int(input().strip())

while True:
    if len(alive) == 2:
        i, j = alive
        d = query(i, j)
        if d == 0:
            print(i, j, flush=True)
        else:
            print(i, j, flush=True)
        break

    pivot = alive[0]
    groups = {}

    for x in alive:
        if x == pivot:
            continue
        d = query(pivot, x)
        groups.setdefault(d, []).append(x)

    next_alive = None
    for g in groups.values():
        if len(g) >= 2:
            candidate = [pivot] + g
            next_alive = candidate
            break

    if next_alive is None:
        next_alive = alive

    alive = next_alive
```实现维护一个工作集`alive`包含仍可能保存重复项的索引。 每次迭代都会选择一个枢轴并查询从它到所有其他活动索引的距离。 分组步骤至关重要，因为相同的字符串必须与枢轴产生相同的距离，因此它们总是落在同一个桶中。 

选择至少两个大小的组是关键的修剪步骤。 这是重复对必须驻留的位置。 一旦找到，我们限制活动集并重复。 

当只剩下两个索引时，终止条件就会发生，此时我们直接查询它们以确认距离为零。 

每次查询和输出后都会刷新一个微妙的细节，这在交互式问题中是强制性的。 另一个是确保我们在缩小集合时始终保留候选对的两个元素，因为错误地删除主元会丢失重复项的一侧。

 ## 边缘情况

 关键的边缘情况是主元本身是重复对的一部分。 假设索引 i 和 j 相同，并且我们选择 i 作为主元。 然后从 i 到所有其他节点的查询会产生 i 和 j 相对于每个其他节点的相同距离。 这保证了它们位于同一组中，因此算法永远不会错误地将它们分开。 作为解决方案集一部分的枢轴实际上增强了正确性，而不是损害它。 

另一种边缘情况是，由于随机性，多个组的大小大于 1。 即使发生不相关的碰撞，重复对仍然存在于一组中，并且由于它是唯一真正相同的对，任何保留大小≥2组的细化步骤最终都会将其隔离。
