 ## 解决方案
 ## 问题理解

 每个游戏都包含一系列$N$匹配。 分数从 1 开始，每场比赛要么将当前分数乘以$A$, 乘以$B$，或者如果没有人解决问题则保持不变。 

关键点是我们没有选择单个序列。 我们必须考虑每一种可能的比赛独立解决方式：每场比赛都有三种可能性，但其中两种会影响比分。 如果至少一场比赛由不同的人解决，则两场比赛被视为不同。 

对于每个这样的完整结果序列，我们计算最终分数，然后将所有可能序列的这些分数相加。 

输入给出了多个测试用例，每个测试用例都有$N$,$A$， 和$B$。 我们必须输出所有有效结果序列的分数总和$10^9 + 7$。 

约束允许最多$10^5$测试用例和$N$最多$1000$。 这立即排除了任何试图枚举结果的解决方案，因为即使对于单个测试用例也有$3^N$的可能性。 该解决方案必须汇总每个职位的贡献或使用封闭式组合结构。 

出现微妙的边缘情况时$A = B = 1$。 在这种情况下，每个序列都会产生分数 1，因此答案正是序列的数量，即$3^N$。 任何除以的导数$A - B$或者假设不进行检查的可逆性将在这里失败。 另一个边缘情况是$A = B \neq 1$，其中对称性使结构崩溃，并且取消的朴素公式再次被破坏。 

## 方法

 暴力解释将每场比赛视为在三个结果中独立选择：佛朗哥解决、拉法解决或无人解决。 对于固定序列，分数是沿序列的贡献的乘积。 这直接导致$3^N$序列，每个需要$O(N)$乘法来评估，即使对于$N = 30$。 

关键的观察是乘法分布在独立的选择上。 我们可以考虑每场比赛贡献一个独立于所有序列的因素，而不是考虑完整的序列。 对于每场比赛，我们有效地总结了三种选择的贡献：乘以$A$, 乘以$B$，或乘以 1。 

这意味着当展开所有序列时，总和因式分解。 每个位置贡献一个乘法因子，等于其在所有选择中的局部贡献之和，并且由于选择在各个位置之间是独立的，因此全局答案成为该局部总和的幂。 

在每场比赛中，对总和的可能贡献为：

 - 1 如果没人解决，
 -$A$如果佛朗哥解决了
 -$B$如果拉法解决了。 

所以每个位置都有一个因素$1 + A + B$。 由于所有位置都是独立的，因此所有序列的总和为：$$(1 + A + B)^N.$$这将整个问题简化为快速模幂运算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(3^N \cdot N)$|$O(1)$| 太慢了|
 | 最佳|$O(T \log N)$|$O(1)$| 已接受 |

 ## 算法演练

 ### 通过模幂进行优化计算

 1. 对于每个测试用例，请阅读$N$,$A$， 和$B$。 问题的整个结构仅取决于通过表达式的这些值$1 + A + B$。 
2. 计算基值$x = (1 + A + B) \bmod (10^9 + 7)$。 这代表了对所有可能结果求和后单场比赛的总贡献。 
3. 计算$x^N \bmod (10^9 + 7)$使用二进制求幂。 此步骤汇总所有比赛的独立贡献。 
4. 输出结果。 

二进制求幂是必要的，因为直接乘法$N$对于大的来说时间太慢$N$并重复$10^5$测试用例。 

### 为什么它有效

 每场比赛对每个完整的游戏配置都有独立的贡献。 当对所有配置求和时，我们有效地展开相同总和的乘积：$$\prod_{i=1}^{N} (1 + A + B).$$由于职位之间不存在交互作用，因此任何术语都不会依赖于其他职位的决策。 这种独立性保证了跨位置的乘法正确地重建了完整的组合展开，而不会过度计数或丢失任何序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modexp(a, e):
    res = 1
    while e:
        if e & 1:
            res = (res * a) % MOD
        a = (a * a) % MOD
        e >>= 1
    return res

t = int(input())
for _ in range(t):
    n, a, b = map(int, input().split())
    base = (1 + a + b) % MOD
    print(modexp(base, n))
```核心思想是将整个组合过程简化为单个幂计算。 功能`modexp`实现二进制求幂，确保每个测试用例的对数时间。 

一个常见的陷阱是忘记中性的“无法解决”结果，这会导致$1$在基地里。 缺少它会导致计算$(A + B)^N$，它会低估跳过匹配的所有序列。

 ## 边缘情况

 当$A = 0$和$B = 0$，只有“无法解决”的结果才有贡献。 底数变为1，所以答案是$1^N = 1$。 该算法直接通过基础计算来处理这个问题。 

什么时候$A = B = 1$，每场比赛的贡献均等，底数变为3。答案是$3^N$，匹配所有可能结果序列的数量。 任何错误地简化对称性的方法都可能会意外地将其折叠为 1 或$2^N$，但求幂公式保留了正确性。 

什么时候$A$和$B$很大时，模数归约仅发生在基础计算和求幂步骤中。 由于所有算术自始至终都是模块化的，因此避免了溢出并且中间值保持有界。
