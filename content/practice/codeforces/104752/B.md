 ## 解决方案
 ## 问题理解

 我们正在尝试构建一个二进制字符串，但我们无法无限制地自由选择其结构。 我们得到了一些 0 和 1，并且还被告知相同字符的运行长度是有上限的。 有效字符串不得超过可用的 0 或 1 数量，并且还必须避免在任何连续块中包含太多连续的 0 或太多连续的 1。 

任务不是构造显式字符串，而是确定在这些约束下可以形成的任何有效二进制字符串的最大可能长度。 

输入给出四个值。 前两个是我们可以使用多少个零和一个的预算。 最后两个限制游程长度：连续零的块不能超过零游程限制，连续的块不能超过一游程限制。 

考虑构造的一个有用方法是，任何有效字符串都是由交替的 0 和 1 块组成。 每个块都有一个最大大小，总长度只是我们在用完零或一之前设法容纳的所有块的总和。 

约束足够大，每个参数最多一百万，这排除了对所有可能的字符串的任何模拟或对安排的贪婪回溯。 任何二次或指数的事情都是不可能的。 即使对所有可能的分割进行线性扫描也是不必要的，因为结构减少到了少量恒定数量的有意义的配置。 

一些边缘情况很重要。 

如果任一运行限制为零，则该字符根本无法出现。 例如，如果 M0 为零但 C0 为正，则零不能放置在任何地方，因为即使是单个零也会违反约束。 在这种情况下，只有个人可以捐款，但须遵守 M1。 

如果 M0 和 M1 都为零，则不可能有长度超过零的字符串。 

当一个字符丰富而另一个字符非常有限时，就会出现另一种微妙的情况。 例如，C0 = 1000、C1 = 1、M0 = 10、M1 = 1。最好的安排不仅仅是“首先使用全零”，因为运行会强制交替并限制零如何围绕单个零进行分组。 

一个幼稚的错误是假设我们可以独立地为每个块取 min(C0, M0) 个零，并为每个块取 min(C1, M1) 个零，然后对任意多个块求和。 这忽略了块必须交替，并且块的数量受到先用完的字符的限制。 

## 方法

 暴力方法会尝试通过递归或迭代构建来构造最长的有效二进制字符串，在跟踪当前游程长度和剩余配额的同时决定在每一步是否附加零或一。 这在概念上是有效的，因为它直接尊重约束，但它探索了巨大的状态空间。 每个位置最多有两种选择，在最坏的情况下会导致指数级增长。 即使使用记忆，状态也包括剩余计数和当前游程长度，这仍然导致非常大的 DP 空间高达 O(C0 * C1 * M0 * M1)，这对于限制来说太大了。 

关键的观察结果是，最佳字符串总是尽可能使用完整的运行容量。 在任何块内，没有理由提前停止，因为在运行中保留未使用的容量只会缩短字符串。 因此，每个块要么是 M0 个零长，要么直到零耗尽，对于 1 也是如此。 

因此，该结构折叠成交替的段：我们重复放置一个大小最多为 M0 的零块，然后放置一个大小最多为 M1 的块，或者反过来。 唯一剩下的决定是我们从哪个角色开始，因为起始角色会影响在一个资源耗尽之前我们可以容纳多少个完整的块。

因此，我们计算两个起始选择的最佳可能长度并取最大值。 每个模拟的块数都是线性的，但由于每个步骤至少消耗一个完整的块容量，因此步骤数受到 O((C0 / M0) + (C1 / M1)) 的限制，这相对于输入大小来说很小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(C0 + C1) 递归 | 太慢了|
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们通过测试两种可能的结构来计算答案：从一组 0 开始或从一组 1 开始。 

1. 我们定义一个辅助函数，模拟在固定起始字符选择下贪婪地构建字符串。 该函数维护剩余的 0、剩余的 1 和一个指示轮到谁放置块的标志。 此结构捕获了有效字符串交替运行的事实。 
2. 当轮到零时，我们在剩余的零和 M0 之间放置一个大小等于最小值的块。 我们从零预算中减去该金额。 这是最佳的，因为任何较短的放置只会减少总长度，而不会提高后续步骤的可行性。 
3.轮到一个人的时候，我们同样放置一个大小为min(剩余的，M1)的块，然后减去它。 这确保了每个块在约束下都被最大限度地填充。 
4. 我们交替轮流，直到两个角色都无法做出进一步的贡献。 当剩余计数都为零或字符耗尽并且无法形成其所需类型的单个有效块时，该过程停止。 
5. 我们分别计算从 0 开始产生的总长度和从 1 开始产生的总长度，然后取最大值。 

一个关键的微妙之处是处理一个字符甚至无法形成单个有效块的情况。 如果 M0 为零并且我们应该放置一个零块，则该分支立即变得无效。 这是通过从该配置返回零贡献来处理的。 

### 为什么它有效

 在有效构造中的任何点，如果我们放置给定字符的块，则使用小于允许的最大运行大小的任何内容都是次优的，因为它无助于未来的可行性并严格减少总长度。 由于每次运行后必须强制切换字符，因此唯一有意义的结构是最大运行序列。 因此，每个最优解对应于两个交替最大运行模式之一，从任一字符开始，其中最好的就是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build(c0, c1, m0, m1, start_zero):
    z, o = c0, c1
    total = 0
    turn_zero = start_zero

    while True:
        if turn_zero:
            if z == 0:
                break
            if m0 == 0:
                break
            take = min(z, m0)
            if take == 0:
                break
            z -= take
            total += take
        else:
            if o == 0:
                break
            if m1 == 0:
                break
            take = min(o, m1)
            if take == 0:
                break
            o -= take
            total += take
        turn_zero = not turn_zero

    return total

def solve():
    c0, c1, m0, m1 = map(int, input().split())

    ans1 = build(c0, c1, m0, m1, True)
    ans2 = build(c0, c1, m0, m1, False)

    print(max(ans1, ans2))

if __name__ == "__main__":
    solve()
```功能`build`模拟贪婪交替结构。 它始终消耗当前运行中允许的尽可能多的符号，确保运行不会超出其限制。 当由于字符耗尽或零运行限制而无法形成所需的块时，模拟将停止。 

我们显式地尝试两种起始配置，因为第一个字符决定如何将资源划分为块。 最终的答案是两者中的最大值。 

该实现避免了任何逐字符模拟。 每次迭代都会删除整个块，这保证了恒定时间收敛。

 ## 边缘情况

 一种边缘情况是运行限制为零。 例如，输入`5 5 0 3`意味着根本不能出现零。 该算法的零启动模拟在第一个零转时立即失败，因为`m0 == 0`，因此它从该分支返回零贡献。 一开始分支正确生成`min(5,3) + 0 = 3`。 

另一个边缘情况是对称的小输入，例如`1 1 1 1`。 两种起始策略都会产生长度 2，因为我们可以按任意顺序放置一个 0 和一个 1。 模拟交替一次，并在耗尽两种资源后停止。 

第三种情况是严重不平衡的限制，例如`100 1 50 1`。 从零开始产生一个零，然后产生一个一，总共 2 个，而从 1 开始仅产生 1 个。该算法正确地识别出，首先从稀缺字符开始允许在被阻止之前稍微更好地利用。
