 ## 解决方案
 ## 问题理解

 我们有一个回合制游戏，在几个独立的场景中进行。 每个场景都包含气球束的集合，其中每个气球束包含一定数量的气球。 轮到玩家时，他们只选择一个捆绑包并删除其中一个$A$,$B$， 或者$C$只要所选数量不超过该捆绑包的大小即可。 如果捆绑包的移动大小少于所有三个允许的移动大小，则仅允许从中进行可行的删除。 在自己的回合中无法做出任何有效动作的玩家就输了。 

除了共享相同的移动规则之外，捆绑包之间没有任何交互，因此每个捆绑包的行为就像具有移动集的减法游戏中的独立堆一样$\{A, B, C\}$。 一轮包括拾取一堆并应用一次有效的减法。 

每个查询都会询问该游戏位置的第一个玩家是否有获胜策略，并且我们必须输出哪个指定玩家最终获胜，假设双方都处于最佳状态。 

这些限制强烈推动预计算。 最多有$10^5$查询，每个查询最多可以包含$10^3$捆绑包，捆绑包大小可达$10^6$。 每个查询直接进行博弈树搜索是不可能的，因为即使是单个堆的大小$10^6$分支因子高达 3 会产生指数状态空间。 在最坏的情况下，即使每个查询重新计算的每个包动态编程也会太慢。 

一个微妙的边缘情况来自于正确解释“选择一个捆绑包并移除 A/B/C 气球”。 这一举动不是“从总和中选择A/B/C”，而是独立地应用于恰好一堆。 将其误读为全局减法游戏会导致堆大小的聚合不正确。 

另一个重要的边缘情况是相同的捆绑包并不特殊。 两个不同的查询可能共享相同的桩值，但是除非我们利用移动集本身的结构，否则跨查询不会重用。 

## 方法

 暴力方法将每个查询视为完全公正的游戏状态$K$堆并尝试计算该位置的 Grundy 值。 从单一状态开始，一次移动包括选择一个堆并将其减少$A$,$B$， 或者$C$，因此状态图最多连接到$3K$新的状态，每个状态都有一个坐标不同。 这使得国家空间巨大，即使对于温和派来说也是如此。$K$，因为每个堆的范围可达$10^6$，并且不同配置的数量呈指数增长$K$。 

即使我们独立地简化并计算每个堆的 DP 直到其值，每个查询都需要这样做$O(K \cdot 10^6)$在最坏的情况下进行每次测试，这远远超出了限制。 

关键的观察结果是，该游戏是相同减法游戏的析取和。 每个束都是类似 Nim 结构的堆。 Sprague-Grundy 定理告诉我们整个位置简化为独立堆 Grundy 值的异或。 所以任务变成了计算$g(x)$，单个堆大小的 Grundy 值$x$，其中移动是减去$A$,$B$， 或者$C$。 

自从$A, B, C \le 100$，每个的过渡$x$仅取决于最多三个较小的州。 这使得简单的 DP 可行至$10^6$一次，在所有查询之间共享。 

每个查询的最终答案只是 XOR$g(K_i)$覆盖所有捆绑包。 如果 XOR 非零，则起始玩家获胜； 否则他们就输了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解游戏树 | 指数| 指数| 太慢了|
 | DP + 斯普拉格-格伦迪 |$O(M + \sum K)$预计算后 |$O(M)$| 已接受 |

 这里$M = 10^6$，最大堆大小。 

## 算法演练

 1. 预先计算一个DP数组`grundy[x]`为所有人$x$从 0 到查询中可能出现的最大堆大小。 这是必要的，因为每个桩状态仅取决于较小的值。 
2. 设置`grundy[0] = 0`，因为没有气球的一堆没有合法的移动并且根据定义正在丢失。 
3. 对于每个值$x$，通过减去来计算可达状态集$A$,$B$， 或者$C$，前提是结果保持非负值。 
4. 将所有可达状态的Grundy 值收集到一个集合中。 
5. 计算`grundy[x]`作为 mex，不在可达集中的最小非负整数。 这捕捉了公正博弈中格伦迪数的定义。 
6. 对于每个查询，初始化一个累加器`xor_sum = 0`。 
7. 对于每个捆绑尺寸$k_i$, 异或`xor_sum`和`grundy[k_i]`。 这将独立的子游戏聚合到一个位置。 
8.如果`xor_sum`非零，则起始玩家有获胜棋步，否则该位置失败。 

这样做的原因是每次移动都会影响一个堆，因此游戏分解为独立的子游戏，其值在 XOR 下组合。 DP 确保每个堆值单独编码该堆内的最佳游戏，而 XOR 捕获最佳策略选择下的跨堆交互。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    first = input().strip()
    A, B, C, Q = map(int, input().split())

    moves = (A, B, C)
    max_val = 10**6

    grundy = [0] * (max_val + 1)

    for x in range(1, max_val + 1):
        reachable = set()
        for m in moves:
            if x >= m:
                reachable.add(grundy[x - m])
        g = 0
        while g in reachable:
            g += 1
        grundy[x] = g

    def winner(xor_sum):
        if xor_sum != 0:
            return "Happy Bruce" if first == "Bruce" else "Sad Arthur"
        else:
            return "Sad Arthur" if first == "Bruce" else "Happy Bruce"

    out = []
    for _ in range(Q):
        K = int(input())
        arr = list(map(int, input().split()))
        x = 0
        for v in arr:
            x ^= grundy[v]
        out.append(winner(x))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```DP 表使用自下而上的递归方式构建一次，其中每个状态仅取决于最多三个先前条目，这使每个值的转换时间保持恒定。 这里的 mex 计算很简单，因为可达集的大小最多为 3，所以我们只测试几个候选者。 

然后，每个查询都会减少为对预先计算的值进行异或累积，从而使查询处理与包的数量呈线性关系。 

最终的玩家姓名逻辑决定了谁开始游戏，因为获胜的异或位置的含义取决于视角。 非零异或意味着游戏开始时当前玩家有获胜策略。

 | --- | --- | --- |
 | 时间 |$O(M + \sum K)$| 所有桩尺寸的 DP 预计算可达$M$，加上所有查询堆的线性扫描 |
 | 空间|$O(M)$| 每个堆大小的 Grundy 值的存储 |

 预计算结束$10^6$状态在 Python 中是可以接受的，因为每个状态仅在一个小集合上执行三个转换和一个恒定时间 mex。 查询处理纯粹是异或累积，在给定输入大小的情况下这是最佳的。

 ## 边缘情况

 一种重要的边缘情况是所有移动大小都超过堆大小。 例如，如果$A=7, B=8, C=9$一堆有大小$5$，则不可能进行任何移动，Grundy 值为 0。DP 正确分配 0，因为可达集为空且 mex 为 0。 

另一种情况是多次移动导致相同的结果状态。 如果$A=2, B=4, C=6$和$x=6$， 两个都$6-2=4$和$6-4=2$是有效的，同时$6-6=0$。 可达集变为$\{g(4), g(2), g(0)\}$，并且 mex 是在此重复数据删除集上计算的，因此重复的值不会扭曲结果。 

第三种情况是 XOR 跨堆抵消时。 例如，如果两堆具有相同的 Grundy 值，则它们的 XOR 为零，这意味着它们形成失败的对。 该算法自然地处理了这个问题，因为异或在所有桩上统一应用，无需特殊外壳。
