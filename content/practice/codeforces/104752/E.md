 ## 解决方案
 ## 问题理解

 这家商店有一个固定的纸币面额，每件商品都有美元价格。 一名游客想要购买某件商品，但胡安只能使用该一种面额的钞票。 任务是确定需要多少张此类钞票才能使其总价值达到商品价格。 

由于每张账单都准确贡献$A$美元，我们正在有效地分解价格$B$成倍数$A$。 如果价格不能完全整除，我们仍然需要足够的账单来完全覆盖它，因为在这种解释中不允许少付。 这将问题转化为计算最小整数$k$这样$k \cdot A \ge B$。 

约束条件达到$10^9$，因此任何解决方案都必须在每个测试用例的恒定时间内运行。 迭代或模拟添加账单最多需要$10^9$最坏情况下的步骤，远远超出 1 秒的限制。 这立即表明答案必须使用算术而不是模拟来得出。 

一个微妙的边缘情况是$B$正好可以整除$A$。 例如，如果$A = 5$和$B = 10$，答案正是 2。如果$A = 5$和$B = 11$，答案就变成了 3，而不是 2，因为两张钞票只给出了 10，这是不够的。 

另一个极端情况出现时$A > B$。 例如，$A = 10$,$B = 3$。 需要一张账单，因为不可能分期付款，而且零账单也无法支付费用。 

## 方法

 暴力方法会反复减去$A$从$B$直到余数变为非正数。 这是正确的，因为每次减法都对应于使用一张钞票。 然而，在最坏的情况下$A = 1$和$B = 10^9$，这需要$10^9$迭代，这太慢了。 

关键的观察是我们正在计算有多少个完整的大小块$A$适合$B$，如果还有余数，可能还加上一个额外的块。 这正是分区的上限$B / A$。 一旦我们认识到这一点，问题就简化为单个整数算术运算。

 | 吊顶事业部|$O(1)$|$O(1)$| 已接受 |

 ## 算法演练

 ### 最优策略

 1. 读取整数$A$和$B$。 这些代表固定票据价值和所需的付款金额。 
2. 计算是否$B$可以整除$A$。 如果是的话，答案就是$B / A$，因为钞票完美贴合，没有浪费。 
3.如果$B$不能被整除$A$, 计算$B // A + 1$。 整数除法给出了适合的完整账单的数量，额外的一个覆盖了剩余的未付金额。 
4. 输出计算值。 

关键的决策点是剩余部分的处理。 如果我们忽视它，我们就会少付钱；如果我们忽视它，我们就会少付钱。 如果我们通过额外的一笔账单进行过度补偿，我们总是以最小的超额达到或超过目标。 

### 为什么它有效

 任何解都对应于选择一个整数$k$这样$kA \ge B$。 这些整数的集合开始于$\lceil B/A \rceil$。 任何较小的值$k < \lceil B/A \rceil$意味着$kA < B$，无法覆盖价格。 任何更大的值都会不必要地增加成本。 因此，天花板划分是唯一的最小有效选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

A = int(input().strip())
B = int(input().strip())

# compute ceiling of B / A
ans = (B + A - 1) // A

print(ans)
```该解决方案依赖于经典的整数上限技巧。 它没有显式检查整除性，而是使用恒等式$\lceil B/A \rceil = (B + A - 1) // A$。 这避免了分支并将计算保留在单个算术表达式中。 

分子内减 1 可确保精确倍数不会被错误地舍入。 例如，当$B = 10$和$A = 5$，我们得到$(10 + 4) // 5 = 2$，而当$B = 11$，我们得到$(11 + 4) // 5 = 3$。

 ## 边缘情况

 当$A = 1$，每一美元需要一张钞票。 该算法计算$(B + 0) // 1 = B$，无需特殊处理即可产生正确的线性结果。 

什么时候$A > B$， 说$A = 10$,$B = 3$，公式给出$(3 + 9) // 10 = 1$。 这符合即使超额支付也必须至少使用一张账单的要求。 

什么时候$B$恰好是$A$， 例如$A = 5$,$B = 20$，表达式产生$(20 + 4) // 5 = 4$，避免不必要的四舍五入并确认上限公式的紧密性。
