 ## 解决方案
 ## 问题理解

 我们被要求计算有多少个长度的序列$n$可以使用以下数字组成$1$到$k$，但仅限于那些同时存在三个结构规则的序列。 

该序列具有固定的奇数长度，因此具有唯一的中间位置。 中间的元素被强制精确地$k$，序列中没有其他地方是$k$允许出现。 所以价值$k$其行为就像一个特殊的标记，固定中心并禁止在其他地方重复。 

远离中心，序列不是自由的：位置通过加倍约束连接在一起。 如果我们看中心左侧或右侧的位置，那么任何距离的位置$d$距中心的位置必须与远处的位置相匹配$2d$。 这会沿着指数创建等值链$d, 2d, 4d, \dots$。 所以该序列不再是一个自由数组； 它会分解为通过将偏移量反复乘以二而形成的相等类。 

最重要的是，对相邻对有限制。 我们被放弃$m \le 16$有序对$(x_i, y_i)$。 每个这样的有向对最多允许在整个序列中作为连续子串出现一次。 如果一对出现两次，即使在不同的位置，该序列也是无效的。 

限制以非常具体的方式很小：$k \le 10$和$n \le 53$。 这立即表明对所有序列进行暴力破解是不可能的，而且对禁止对进行位掩码的状态空间动态编程方法是合理的。 

不明显的困难是双重等式约束。 天真的 DP 必须确保相距甚远但被迫平等的立场之间的一致性。 如果忽略这一点，人们就会错误地将头寸视为独立头寸并进行多算。 

当一个位置被提前分配，并且属于同一双链的较晚的位置收到冲突的值时，就会出现典型的失败情况。 例如，如果位置$d$设置为$1$，然后定位$2d$也必须是$1$，但天真的 DP 可能会独立分配它并计算无效序列。 

另一个微妙的失败来自邻接跟踪。 由于每个禁止对在全局范围内最多出现一次，因此贪婪的局部检查是不够的； 我们必须跟踪整个序列的全局使用情况。 

## 方法

 蛮力方法很简单：枚举每个长度的序列$n$，检查中心条件是否成立，验证所有加倍等式，并扫描所有相邻对，同时跟踪禁止对的出现。 这在概念上是有效的，因为每个条件都很容易验证$O(n)$，所以总复杂度是$O(k^n \cdot n)$。 和$k \le 10$和$n \le 53$，这是一个天文数字，而且立即不可能。 

关键的观察结果是加倍约束不会引入任意依赖性； 它只强制沿由重复乘以 2 定义的链相等。 每个位置都属于一个这样的链，这意味着序列不是任意的，而是由少量“变量”组成，每个变量代表一个完整的等价类位置。 

这允许对从左到右的位置进行动态编程解释。 每当我们遇到一个位置，其值已经由之前看到的等效位置确定时，我们就不会分支。 当我们遇到一个新的等价类代表时，我们为它选择一个值。 因为$k$虽然很小，但这种分支仍然是可管理的。 

为了处理禁止对，我们使用已用对的位掩码来增强 DP 状态。 每次我们放置两个相邻的值时，我们要么忽略它（如果不禁止），要么将相应的对标记为已使用。 如果一对被使用两次，我们拒绝该分支。 

“等价类的按需分配”和“禁止转换上的位掩码 DP”的结合使该解决方案变得可行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举|$O(k^n \cdot n)$|$O(n)$| 太慢了|
 | 具有等价 + 位掩码的 DP |$O(n \cdot k \cdot 2^m)$|$O(n \cdot 2^m)$| 已接受 |

 ## 算法演练

 我们从左到右处理序列，在到达每个位置时对其进行处理。 

1.首先我们固定中心位置$c$并为其赋值$k$。 这个值永远不会再改变，也不允许其他位置使用它。 这会立即锚定涉及该中心的所有邻接检查。 
2.我们预先计算由规则引起的双重等价结构$a_{c+d} = a_{c+2d}$。 对于每个偏移量$d$，我们在边界内重复乘以 2，并将所有这些位置合并为一个分量。 经过这一步后，每个位置都属于一个组件，且其值必须一致。 
3. 我们对以下位置进行 DP$1$到$n$。 在每个步骤中，DP 状态包括当前位置索引、最后放置的值（邻接检查所需）、表示已使用哪些禁止对的位掩码，以及存储迄今为止遇到的组件分配的结构。 
4. 处理位置时$i$，我们首先确定它属于哪个组件。 如果这个组件已经分配了值，我们就被迫使用它。 如果未分配，我们会尝试以下所有值$1$到$k-1$，分配它，然后继续。 
5. 确定位置值后$i$，我们处理邻接关系。 如果$i > 1$，我们看这对$(a_{i-1}, a_i)$。 如果该对是禁止对之一，我们检查它是否以前被使用过。 如果已经出现过一次，则该转换无效。 否则，我们将其标记为已使用。 
6.我们继续直到位置$n$。 只有成功一致地分配所有组件并且从不违反禁止配对规则的序列才能得出答案。 

### 为什么它有效

 正确性取决于以下事实：加倍约束将索引划分为不相交的分量，每个分量必须在整个序列中携带单个值。 DP 确保每个组件都被精确地分配一次，并且永远不会不一致地重新分配。 同时，位掩码保证在整个结构中全局跟踪每个禁止对，因此不会因本地决策而漏掉非法重复。 由于每个有效序列恰好对应于通过该 DP 的一条路径，并且每个 DP 路径都遵循所有约束，因此计数是准确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k, m = map(int, input().split())
    bad = {}
    bad_list = []
    for i in range(m):
        x, y = map(int, input().split())
        bad[(x, y)] = i
        bad_list.append((x, y))

    c = (n + 1) // 2

    comp = [-1] * (n + 1)
    cid = 0

    for i in range(1, n + 1):
        if comp[i] != -1:
            continue
        j = i
        while j <= n:
            comp[j] = cid
            j *= 2
        cid += 1

    # DP state: position, last value, mask, assignments
    from functools import lru_cache

    @lru_cache(None)
    def dp(i, last, mask, assign):
        if i == n + 1:
            return 1

        comp_vals = list(assign)
        c_id = comp[i]
        cur_val = comp_vals[c_id]

        res = 0

        if i == c:
            if 1:  # must be k
                if last != -1:
                    if (last, k) in bad:
                        idx = bad[(last, k)]
                        if mask >> idx & 1:
                            return 0
                        new_mask = mask | (1 << idx)
                    else:
                        new_mask = mask
                    res += dp(i + 1, k, new_mask, tuple(comp_vals))
                else:
                    res += dp(i + 1, k, mask, tuple(comp_vals))
            return res % MOD

        if cur_val != 0:
            v = cur_val
            if last != -1:
                if (last, v) in bad:
                    idx = bad[(last, v)]
                    if mask >> idx & 1:
                        return 0
                    new_mask = mask | (1 << idx)
                else:
                    new_mask = mask
            else:
                new_mask = mask

            res += dp(i + 1, v, new_mask, assign)
        else:
            for v in range(1, k + 1):
                if v == k:
                    continue
                comp_vals[c_id] = v
                if last != -1:
                    if (last, v) in bad:
                        idx = bad[(last, v)]
                        if mask >> idx & 1:
                            continue
                        new_mask = mask | (1 << idx)
                    else:
                        new_mask = mask
                else:
                    new_mask = mask

                res += dp(i + 1, v, new_mask, tuple(comp_vals))
                res %= MOD
            comp_vals[c_id] = 0
            return res

        return res % MOD

    init_assign = tuple([0] * cid)
    print(dp(1, -1, 0, init_assign) % MOD)

if __name__ == "__main__":
    solve()
```该代码首先将加倍约束压缩为连通分量。 每个索引重复加倍，直到超出范围，产生相等组。 

然后摄影指导遍历各个位置。 元组`assign`存储每个组件的当前值，其中零表示未分配。 当第一次看到一个组件时，DP 会在除禁止中心值之外的所有可能值上分支$k$。 

这`mask`禁止定向对已被使用的轨道。 每次形成相邻对时，我们要么设置相应的位，要么拒绝转换（如果已使用）。 

中心位置被特殊处理，因为它被固定为$k$，并且它还与双方的邻接约束相互作用。 

一个微妙的点是赋值元组在每个分支步骤都会被复制。 这是必要的，因为不同的分支不得共享组件分配。 

## 工作示例

 ### 示例：小型对称案例

 考虑一个短序列，其中组件最少并且不存在禁止对。 

| 步骤| 职位| 元件值| 最后值 | 面膜|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 分配 1 | 1 | 0 |
 | 2 | 2 | 继承 1 | 1 | 0 |
 | 3 | 3（中）| k | k | 0 |

 此跟踪显示单个分配如何在组件中传播，从而删除后面位置的分支。 

### 示例：禁止配对激活

 假设我们有一个禁止对 (1,2)。 

| 步骤| 位置 | 价值| 配对 | 面膜|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | - | 0 |
 | 2 | 2 | 2 | (1,2) | 1 |
 | 3 | 3 | 3 | (2,3) | 1 |

 如果 (1,2) 稍后再次出现，DP 会立即拒绝该分支，从而展示全局跟踪。

 ## 边缘情况

 关键的边缘情况是组件跨越多个位置但仅在 DP 中稍后遇到。 在这种情况下，算法会正确地延迟分配直到第一次遇到，从而确保不会过早做出承诺。 

另一个边缘情况是中心邻接。 由于中心固定为$k$，任何涉及的禁止对$k$必须精确追踪； 否则，重复的序列$(x, k)$或者$(k, y)$会被错误地计算在内。 

最后，形成长双链的成分必须在所有情况下保持一致。 DP 通过将分配存储在共享状态中来强制执行此操作，因此重新访问组件永远不会创建冲突分支。
