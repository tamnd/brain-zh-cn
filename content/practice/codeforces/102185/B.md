 ## 解决方案
 ## 问题理解

 商店有一个固定价格`P`。 对于每种产品，我们知道所需的单位数量`A`以及一单位的市场价格`S`。 

商店的行为有所不同，具体取决于一件商品是否已经至少值钱`P`。 如果`S >= P`，可提供单独的单位，每个单位的成本完全相同`P`。 至少要获得`A`单位，我们只需购买`A`单位，所以成本为`A * P`。 

如果`S < P`，单个单位不能购买。 相反，一个包裹的成本`P`并包含`ceil(P / S)`单位。 我们可以购买任意数量的完整包裹，因此任务就变成了找到总单元数至少为 的最小数量的包裹`A`。 

例如，与`P = 100`和`S = 51`, 一包包含`ceil(100 / 51) = 2`单位。 至少要获得`6`单位，我们需要`ceil(6 / 2) = 3`套餐、成本核算`300`。 

最多有`1000`产品，以及每一个`A`和`S`至多是`1000`。 这些界限足够小，甚至需要高达`1000`每个产品的迭代最多执行大约`10^6`迭代。 这样的解决方案会很顺利地通过。 然而，购买规则的结构让我们能够在恒定的时间内解决每个产品，从而给出一个特别简单的方法`O(N)`解决方案。 

主要的边缘情况来自两种定价规则的边界。 什么时候`S = P`，产品是单独出售的，所以对于输入```
1 1004 100
```答案是`400`。 使用包公式的粗心实现可能会计算出包大小`1`并且仍然碰巧得到相同的结果，但是治疗`S = P`因为如果实现假设包包含多个单元，则包的大小写可能会掩盖实际规则并导致错误。 

第二个边缘情况是当`P`不能被整除`S`。 为了```
1 1006 30
```一包包含`ceil(100 / 30) = 4`单位。 两个包给`8`单位，所以答案是`200`。 使用整数除法`100 // 30 = 3`会错误地得出结论，一个包只包含三个单元并产生`200`这里碰巧有六个必需的单位，但是对于```
1 1007 30
```正确答案仍然是`200`，而使用错误的封装大小 3 会产生`300`。 

当所需数量已经小于一包时，就会出现第三个边界。 为了```
1 1001 40
```一包包含`ceil(100 / 40) = 3`单位，所以购买一包就足够了，答案是`100`。 将所需数量乘以固定价格将错误地给出`40`就包裹数量而言，或`100`仅当正确处理区别时。 

## 方法

 直接模拟即可解决问题，重复添加一个包，直到累计单元数达到`A`。 对于具有`S < P`，我们首先计算封装尺寸`K = ceil(P / S)`，然后重复添加`K`直到我们有足够的单位。 在最坏的情况下，`K = 1`，所以这个循环最多执行`A <= 1000`一种产品的迭代。 和`N <= 1000`，也就是至多`10^6`总共迭代次数。 因此，对于给定的约束，这种强力模拟实际上足够快。 

消除循环的观察结果是每个包装都具有完全相同的尺寸和价格。 如果每个包都有贡献`K`单位，然后购买后`x`我们有确切的包裹`xK`单位。 我们需要最小的整数`x`满意的`xK >= A`，这正是`ceil(A / K)`。 因此，整个模拟可以由一个天花板分区代替。 

这两种情况可以合并成一个非常小的计算。 如果`S >= P`，一次购买赠送一单位，因此购买数量为`A`。 否则，一次购买即可获得`K = ceil(P / S)`单位，所以购买数量为`ceil(A / K)`。 每次购买费用`P`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟 |`O(sum A_i)`, 至多`10^6`迭代|`O(1)`| 已接受 |
 | 最佳吊顶划分|`O(N)`|`O(1)`| 已接受 |

 最优方法更可取，因为它直接表达数学条件而不是模拟购买。 它也更容易证明正确性，并且没有迭代计数取决于请求数量的循环。 

## 算法演练

 1. 阅读`N`和固定价格`P`。 接下来的每一个`N`生产线描述一种独立的产品，因此产品可以单独加工。 
2. 对于产品，请阅读所需数量`A`和市场价格`S`。 
3.如果`S >= P`，将购买数量设置为`A`。 在这种情况下，商店出售单个单位，每个单位的成本`P`。 
4. 否则，计算一包中的单位数量：`K = ceil(P / S)`。 由于所有值都是整数，因此上限除法可以写为`(P + S - 1) // S`。 
5. 计算所需的包裹数量为`ceil(A / K)`，再次使用整数算术作为`(A + K - 1) // K`。 
6. 将购买数量乘以`P`并输出该值。 
7. 对所有产品独立重复计算并打印结果成本。 

### 为什么它有效

 对于`S >= P`，商店每付款一次就销售一个单位`P`，所以购买`A`单位准确地要求`A`付款。 

为了`S < P`，每个包都包含准确的`K = ceil(P / S)`单位。 购买后`x`包，我们有`xK`单位。 该算法选择最小的整数`x`为此`xK >= A`，即`ceil(A / K)`。 因此，它购买了足够的单位，而少一包将提供少于`A`单位。 因为每个套餐的价格都是一样的`P`，这个最小数量的包也给出了可能的最小成本。 

## Python 解决方案```python
Pythonimport sysinput = sys.stdin.readline

def solve():    n, p = map(int, input().split())    ans = []
    for _ in range(n):        a, s = map(int, input().split())
        if s >= p:            purchases = a        else:            package_size = (p + s - 1) // s            purchases = (a + package_size - 1) // package_size
        ans.append(purchases * p)
    print(*ans)

if __name__ == "__main__":    solve()
```该程序首先读取产品数量和共同固定价格。 答案会累积在一个列表中，以便所有成本都可以打印在最后一行上。 

条件`s >= p`完全遵循语句的边界。 平等属于单个单位的情况，尽管当`s == p`。 

对于包装盒来说，`(p + s - 1) // s`执行整数上限除法。 写作`p // s`会向下舍入，并可能低估包装中的单位数量。 

第二个上限部分计算至少需要多少个包裹才能到达`a`单位。 乘以`p`仅在确定所需购买数量后才执行。 

Python 整数具有任意精度，因此不存在整数溢出问题。 在给定的约束下，最大可能的答案也很小：最多`1000 * 1000 = 10^6`对于单独出售的单位。

 ## 边缘情况

 当`S = P`，商店出售单个单位。 为了```
1 1004 100
```条件`S >= P`是真的，所以算法设置`purchases = 4`和输出`400`。 在这种情况下不需要创建包。 

什么时候`S`不分开`P`，天花板划分是必不可少的。 为了```
1 1007 30
```包装尺寸为`(100 + 30 - 1) // 30 = 4`。 两个包包含八个单元，足以满足所需的七个单元，所以答案是`200`。 楼层划分会错误地将包裹大小计算为三。 

什么时候`A`小于包装尺寸，仍需一整包。 为了```
1 1001 40
```该套装包含三个单元，但仅要求一个单元。 由于包裹无法拆分，`ceil(1 / 3) = 1`，给出成本`100`。 

当请求的数量正好可以被包裹尺寸整除时，第二个上限分割不得添加不必要的包裹。 为了```
1 1006 50
```一包包含`2`单位，以及`6 / 2 = 3`确切地。 该算法计算`(6 + 2 - 1) // 2 = 3`，所以答案是`300`， 不是`400`。 

最终的边界是`S > P`。 为了```
1 1001 101
```该产品作为一个单独的单元出售`100`，尽管其市场价格较高。 该算法遵循`S >= P`分支和输出`100`。
