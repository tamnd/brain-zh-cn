 ## 解决方案
 ## 问题理解

 我们在平面上得到一系列点，代表以固定顺序访问的恒星。 连续的星星总是水平或垂直对齐，因此星星之间的每次移动$i$和明星$i+1$是平行于轴的直线段。 

对于每一颗星星$i$，我们必须指定一个整数半径$R_i \ge 1$。 该航天器概念上“绕”恒星运行$i$以那个半径。 连续恒星之间的唯一耦合是几何约束：恒星的半径$i$必须严格小于恒星之间的欧几里得距离$i$和明星$i+1$。 

航天器从恒星过渡$i$明星$i+1$在 轨道上的点$i$最接近下一颗恒星，但对可行性唯一重要的部分是不等式$$R_i < d(i, i+1)$$在哪里$d$是欧几里得距离。 

我们被要求选择满足所有约束的有效半径序列并最大化$R_1$。 如果根本不存在赋值，我们输出-1。 

关键的微妙之处在于半径不是独立的：一旦$R_i$被选择，它会影响早期恒星的可能性，因为我们想要最大化$R_1$，不是任意的可行性。 

约束条件很大，最多可达$10^5$点，因此任何解都必须是线性或接近线性的。 任何与序列成二次方的东西都会立即变得太慢。 

一些失败案例自然会出现。 

例如，如果两个连续的星星非常接近$(0,0)$和$(0,1)$，距离为1，所以$R_1$必须为 0，这是不可能的，因为半径必须至少为 1。这使得整个配置变得不可能。 

当所有边缘都长（除了一个早期边缘短）时，会发生更微妙的故障。 例如，如果第一条边的距离为 2，但后面的边很大，我们可能会认为我们可以选择$R_1 = 1$，但事实上，后期的约束可能会根据半径的传播方式强制产生矛盾，因此我们需要一致的全局构造。 

主要困难是理解约束如何从结束向后传播到开始。 

## 方法

 一个天真的解释是尝试从左到右分配半径。 对于每个$i$，我们选择$R_i$下尽可能大$R_i < d(i, i+1)$，然后继续。 这最大化了每个局部值，但它忽略了最大化的全局目标$R_1$在存在完全可行的分配的情况下。 这种贪婪的前向方法不能保证最大化$R_1$，因为尽早选择小半径可能会不必要地限制可行性模式，而这些模式可能允许更大的半径$R_1$在不同的分布下。 

另一种暴力方法是处理$R_1$修复并检查可行性：如果我们修复$R_1 = x$，我们可以构造$R_2, \dots, R_N$？ 然后我们就可以二分查找$x$。 然而，即使天真地检查可行性也需要探索后续半径的许多选择，可能是指数的，因为每个半径都有一个范围$[1, d(i,i+1)-1]$。 

关键的观察是，唯一的约束是局部上限，并且除了全局最小值之外，不同半径之间没有直接的下限依赖关系$R_i \ge 1$。 这意味着每个$R_i$一旦我们确保它尊重自己的边缘约束，就可以始终独立选择。 之间没有传播约束$R_i$和$R_{i+1}$。 

因此可行性简化为一个简单的条件：每条边的距离必须至少为 2，因为我们需要$R_i \ge 1$和$R_i < d(i,i+1)$， 所以$d(i,i+1) \ge 2$。 一旦成立，我们就可以随时设置$R_i = 1$为所有人$i$，以及任何更大的$R_1$仅受其传出边缘的约束。 

因此，影响的唯一真正的约束$R_1$是第一条边：$R_1 < d(1,2)$。 自从$R_1$是一个整数，最大值是$d(1,2) - 1$，前提是所有边都有效（距离至少为 2）。 如果任何边的距离为 1，则答案为 -1。 

这将整个问题简化为计算连续点之间的欧几里德距离并检查有效性。

 ## 算法演练

 1. 按顺序读取所有点并计算连续点之间的欧氏距离平方。 平方距离避免了浮点精度问题，同时保留了顺序，因为我们只与整数进行比较。 
2.对于每个连续的对，检查平方距离是否至少为4。这相当于要求真实距离至少为2，这样保证了整数半径$R_i \ge 1$可以满足$R_i < d(i,i+1)$。 
3. 如果任何连续对的平方距离等于 1，则立即断定该配置是不可能的。 这对应于相距一个单位的两个点，不存在严格小于 1 的整数半径。 
4. 单独跟踪第一个边缘距离，因为它直接边界$R_1$。 让$d_1$是星 1 和星 2 之间的欧几里德距离。 
5. 如果所有边都有效，则将答案计算为$d_1 - 1$，使用基于平方距离的整数算术。 

### 为什么它有效

 每个半径$R_i$仅受下一颗星星的约束，不依赖于之前的选择。 该系统不会施加链接约束，例如$R_i \le R_{i+1}$反之亦然。 因此，可行性分解为每条边的独立约束，并最大化$R_1$仅取决于其直接边缘。 一旦所有边都承认至少一个有效的整数半径，我们总是可以分配$R_i = 1$为所有人$i \ge 2$，并设置$R_1$处于其最大允许值，而不影响任何下游约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    x = []
    y = []
    for _ in range(n):
        xi, yi = map(int, input().split())
        x.append(xi)
        y.append(yi)

    def dist2(i):
        dx = x[i] - x[i+1]
        dy = y[i] - y[i+1]
        return dx*dx + dy*dy

    # check feasibility
    for i in range(n - 1):
        d2 = dist2(i)
        if d2 < 4:
            # distance < 2 means no integer radius >= 1 works
            if d2 == 1:
                print(-1)
                return

    # compute answer from first edge
    dx = x[0] - x[1]
    dy = y[0] - y[1]
    d2 = dx*dx + dy*dy

    # since d >= 2, sqrt(d2) is integer only in axis-aligned case
    # but we only need floor(sqrt(d2)) - 1
    # here distances are integer but can be sqrt(2), sqrt(5), etc.
    # radius must be integer < sqrt(d2)
    import math
    d = math.isqrt(d2)
    if d * d == d2:
        # perfect square distance
        d_exact = d
    else:
        # non-perfect square, actual sqrt is between d and d+1
        d_exact = math.sqrt(d2)

    # correct integer result is floor(sqrt(d2)) - 1
    print(math.isqrt(d2) - 1)

if __name__ == "__main__":
    solve()
```该解决方案读取所有坐标并检查每个连续的段。 通过确保没有线段的距离恰好为 1 来强制实施可行性条件。这是唯一不可能的情况，因为它阻止了该顶点处的任何整数半径。 

最终答案仅取决于第一部分。 由于半径是严格小于距离的整数，因此最大整数是严格低于前两点之间的欧几里德距离的最大整数，该距离是使用整数平方根计算的。 

代码使用`math.isqrt`以避免浮点错误。 草案中的中间浮点计算实际上并不需要，在概念上被平方根减一的整数下限取代。

 ## 边缘情况

 最脆弱的情况是当连续对的距离恰好为 1 时。对于输入```
2
0 0
1 0
```距离平方为1，立即触发失败。 该算法在任何计算之前检测到这一点$R_1$，直接产生-1，这符合没有整数半径满足的事实$1 \le R_i < 1$。 

另一种边缘情况是第一个段很长但后面的段很短。 例如：```
3
0 0
100 0
100 1
```第一个边缘允许大$R_1$，但第二条边的距离为 1，因此可行性失败。 扫描在第二段捕获此情况并在计算答案之前拒绝该实例，从而防止仅基于第一个边缘的不正确的乐观输出。
