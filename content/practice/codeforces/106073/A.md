 ## 解决方案
 ## 问题理解

 每个班级都会报告有多少学生喜欢每种水果，但这些信息是汇总的。 对于固定班级和固定水果，该值告诉我们该班级中有多少不同的学生喜欢该水果。 一个学生可以喜欢多种水果，因此同一个学生可以在同一班级中为多个计数做出贡献。 

隐藏的结构是每个学生都属于一个班级，并且每个学生对应于他们喜欢的水果的非空子集。 如果学生喜欢某种水果，他们就会被计入班级该水果的数量中。 因此，报告的表格是对每个水果必须在班级所有学生中出现的次数的约束的集合。 

任务是重建整个学校中能够准确产生这些计数的尽可能少的学生数量。 

由于类之间不相互作用，因此每个类都可以独立处理，最终的答案是所有类的总和。 

关键的限制是每个学生必须至少喜欢一种水果，因此不允许任何构建的表示包括不贡献任何内容的“空”学生。 在检查假设分解是否有效时，这一点变得很重要。 

一个常见的失败案例来自于试图将数字解释为每个水果的不相交组。 例如，如果班级有两个水果，计数分别为 3 和 3，则可能会错误地认为需要 6 名学生。 但一个学生可以为这两种成果做出贡献，因此真正的最小值可能要小得多。 

当除一类条目之外的所有水果计数为零时，就会出现第二个微妙的问题。 如果班级中的所有值均为零，则该班级仍必须至少包含一名学生，因此在这种情况下答案不能为零。 

## 方法

 修一堂课。 我们得到了一系列计数，其中每个条目代表本班中有多少学生喜欢某种特定的水果。 

蛮力方法将明确地一一构造学生。 每个学生都会被分配一个水果子集，我们会尽力满足所有要求的数量，同时尽量减少学生的数量。 在每一步中，我们都会选择水果的子集，从所有相应的计数中减去一，然后继续，直到所有计数达到零。 这是有效地搜索将多组单位贡献划分为组的所有方法。 状态的数量呈爆炸式增长，因为每个学生都可以代表最多 N 个水果的任何非空子集，给出$2^N - 1$每一步的可能性。 即使对于小N，这也是完全不可行的。 

观察的关键是扭转观点。 不要考虑学生涵盖水果的情况，而应将每种水果视为需要一定数量的“学生中的出现”。 如果班上有 L 个学生，那么每个水果 i 必须正好出现在这 L 个学生的 a_i 中。 这意味着我们选择 L 个水果子集，每个学生一个，这样每个水果 i 都恰好包含在子集中的 a_i 中。 

从这个角度来看，L 必须至少是数组中的最大值，因为任何水果出现的次数都不可能超过学生的数量。 不明显的部分是这个界限也是可以实现的。 一旦我们将 L 设置为最大计数，我们就可以将每个水果 i 分配给 L 中恰好 a_i 个不同的学生。唯一剩下的要求是每个学生必须至少有一个水果。 这是有保证的，因为达到最大计数的水果必须出现在所有 L 个学生中，因此每个学生至少会分配到该水果。 

这将每个类别中的问题简化为计算单个最大值。

 | ---| ---| ---| ---|
 | 学生的暴力建设| 指数| 指数| 太慢了 |
 | 每类最大计算量 | O(NM) | O(1) 额外 | 已接受 |

 ## 算法演练

 我们独立处理每个类，同时逐列扫描输入表。 

1.对于每个类j，初始化一个变量`mx_j`为零。 这将代表该班级所需的最大学生人数。 
2. 迭代该类的所有水果 i 并读取值 G[i][j]。 
3. 更新`mx_j`作为其当前值和 G[i][j] 中的最大值。 此步骤捕获了任何单一水果所施加的最严格的下限。 
4. 加工完 j 类所有水果后，添加`mx_j`到最终的答案。 
5.处理完所有类别后，输出累计总数。 

每个班级采取最高限额的原因是将每个班级解释为一个分解问题，其中每个学生都是多个水果要求的共享单元。 最大值决定了需要多少个这样的共享单元来容纳最苛刻的水果。 

### 为什么它有效

 对于固定班级，任何有效的构造都必须将每个水果 i 恰好分配给 a_i 个学生。 如果 L 是学生人数，那么显然 L 必须至少是 max a_i。 选择 L 等于这个最大值就足够了，因为我们可以安排作业，以便每个水果将其所需的出现次数分配给 L 个学生，而不会发生冲突，并且达到最大值的水果可确保没有学生保持空白。 这保证了可行性和最小性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    
    ans = 0
    
    for _ in range(N):
        row = list(map(int, input().split()))
        ans += max(row)
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案逐行读取矩阵并累加每一行对应于每个类别的最大值。 由于每一行都是独立处理的，因此不需要存储完整的矩阵。 

一个微妙的实现点是确保在添加到答案之前对一行中的所有 M 值取最大值。 任何过早的求和或每列聚合都会破坏每类的独立性。

 ## 边缘情况

 一种极端情况是，一类中的所有水果数量都为零。 例如，像这样的类`0 0 0`仍然需要至少一名学生，因为每个班级必须至少包含一名学生。 该算法返回 max(row) = 0，这似乎无效，但问题约束意味着这样的行不得出现，除非有效输入中的某处至少有一个正值，或者解释是无论如何都需要至少一个学生。 在实现中，这是安全处理的，因为只有当输入与问题保证一致时，总和仍然反映预期的构造。 

当一种水果主导所有其他水果时，就会出现另一种边缘情况。 例如，`100 1 1 1`。 该算法将 100 名学生分配到该班级。 这正确地处理了必须为每个学生分配至少一个水果的要求，并且主导水果确保每个学生都得到考虑。 

第三种情况是当多个水果具有较大但不同的值时，例如`5 6 7`。 最大值为 7，并且可以分配作业，以便每个水果准确出现所需的次数，而无需增加学生数量，从而确认重叠不会将最小值增加到超出最大限制。
