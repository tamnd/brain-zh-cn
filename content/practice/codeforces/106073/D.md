 ## 解决方案
 ## 问题理解

 我们得到一小部分多米诺骨牌，每个牌都标有从 1 到 6 的两个数字。如果牌的一端与演化链左端或右端当前暴露的数字相匹配，则牌可以按序列使用。 

该过程是动态的：图块以固定顺序一张一张到达。 第一个图块始终是自由放置的。 从第二个图块开始，每个图块必须附加到当前链的左端或右端，与该侧的暴露数字相匹配。 如果在任何时候都无法在两端放置图块，则该过程会立即失败。 

然而，不同的是，我们可以在过程开始之前丢弃任何图块子集。 对于每个子集，我们询问该子集是否至少存在一种排序，这样，如果按照该顺序绘制图块，Alice 可以成功放置每个图块而不会被卡住。 我们必须计算有多少子集至少承认一种这样的成功排序。 

关键的观察是，顺序不是由我们直接确定的，但我们只需要证明某种顺序的存在。 这从根本上提出了关于在 2 端约束下是否可以将多组边排列成类路径结构的有效顺序构造的问题。 

约束很小：每个测试用例 N 最多为 21。 这立即表明迭代所有子集（最多 2^21）是可行的。 真正的困难是确定每个子集是否存在有效的排序。 

天真的尝试会尝试模拟子集的所有排列。 即使对于大小为 k 的子集，也有 k 个！ 排序，即使对于 10 左右的 k 来说也太大了。另一个天真的想法是模拟贪婪的放置，但仅贪婪会失败，因为过早选择附件侧可能会阻止未来的放置。 

当贪婪的放置陷入进程时，就会出现微妙的失败情况。 例如，对于图块 1-2、2-3、3-1，即使存在有效的顺序，许多贪婪的选择也会导致死胡同，因为正确的顺序需要在每个步骤中仔细选择要扩展的端点。 

因此，真正的挑战是在不枚举排列的情况下决定子集的可行性。 

## 方法

 我们首先考虑对子集的暴力破解和对排列的暴力破解。 对于每个子集，我们尝试所有可能的排列并模拟放置。 模拟本身在子集大小上是线性的，因此这大约变为 O(Σ k!·k)，这在 k = 10 之外是不可行的。 

然后我们转变视角。 该过程构建了一条链，其两个端点随着时间的推移而演变。 在每一步中，都会通过匹配一个端点来添加一个图块，而另一个值将成为新端点。 这相当于在多重图中构建一条行走，其中每个图块都是数字 1 到 6 之间的无向边，并且我们以某种顺序显示边，同时保持当前结构始终是路径的不变性。 

这提出了一种状态压缩的想法：我们不跟踪顺序，而是仅跟踪哪些边已被使用以及当前端点是什么。 由于端点只有 1 到 6，因此只有 36 种可能的端点状态（有序对）。 与最多 2^21 的子集掩码相结合，这变得易于管理。 

我们将可行性解释为：是否存在边的排序，以便我们可以顺序构建一条路径，始终将新边附加到两个端点之一？ 

这自然是对子集和端点状态的动态规划。 从已使用的子集和当前端点定义的状态中，我们尝试添加与任一端点匹配的未使用边缘并转换到新的端点配置。 

与蛮力的区别在于，我们将所有排列分解为状态图上的可达性问题。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个子集的强力排列 | O(2^N · N! · N) | O(2^N · N! · N) | O(2^N · N! · N) | O(N) | 太慢了 |
 | 具有端点状态的 DP 子集 | O(2^N·N·36) | O(2^N·N·36) | O(2^N·36) | O(2^N·36) | 已接受 |

 ## 算法演练

 我们独立地对每个子集进行建模，但重复使用相同的 DP 结构。 

1.修复多米诺骨牌的子集。 我们将确定该子集是否存在有效的排序。 我们将每个多米诺骨牌视为两个数字之间的无向边。 
2. 将 DP 状态定义为 dp[mask][a][b]，这意味着我们可以精确构建 mask 中的边集，并最终得到左端点为 a、右端点为 b 的链。 这捕获了与部分构造相关的所有内容，因为未来的扩展仅依赖于端点。 
3. 通过选择子集中的任何单个边作为起始图块来初始化 DP。 对于图块 (x, y)，我们将 dp[1<<i][x][y] 和 dp[1<<i][y][x] 设置为有效状态。 这反映出第一个图块可以任意定向。 
4. 按大小递增的顺序迭代蒙版。 对于每个可达状态 dp[mask][a][b]，尝试添加未使用的边 (u, v)。 如果 u 匹配 a，我们可以扩展左侧，产生一个新的状态 dp[mask ∪ {edge}][v][b]。 如果 v 与 a 匹配，我们同样得到 dp[mask ∪ {edge}][u][b]。 相同的逻辑对称地适用于右端点 b。 该模型将图块附加到当前链的任一端。 
5. 处理完子集的所有状态后，检查是否有任何 dp[full_mask][a][b] 可达。 如果至少存在一个，则该子集有效。 

我们可以独立处理子集的原因是N很小，并且每个子集的DP仅取决于它自己的边。 

### 为什么它有效

 在每一步中，DP 都会显式地对链的所有可能的有效部分结构进行编码。 不变的是每个 dp[mask][a][b] 对应于产生具有端点 a 和 b 的有效链的真实放置序列。 转换仅添加与端点匹配的图块，从而保留有效性。 相反，任何有效的排序都会精确地引入通过这些状态的一条路径，因为排序的每个前缀对应于一个可达的 DP 状态。 有效结构和 DP 可达性之间的这种双射保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        dom = [tuple(map(int, input().split())) for _ in range(n)]
        
        # DP per subset
        ans = 0
        
        # iterate all subsets
        for mask in range(1 << n):
            edges = []
            for i in range(n):
                if mask & (1 << i):
                    edges.append(dom[i])
            
            if not edges:
                ans += 1
                continue
            
            m = len(edges)
            
            # dp[mask][a][b]
            size = 1 << m
            dp = [[set() for _ in range(7)] for _ in range(size)]
            
            # initialize with each edge
            for i, (a, b) in enumerate(edges):
                dp[1 << i][a].add(b)
                dp[1 << i][b].add(a)
            
            for sm in range(size):
                for a in range(1, 7):
                    for b in dp[sm][a]:
                        for i, (u, v) in enumerate(edges):
                            if sm & (1 << i):
                                continue
                            ns = sm | (1 << i)
                            if u == a:
                                dp[ns][v].add(b)
                            if v == a:
                                dp[ns][u].add(b)
                            if u == b:
                                dp[ns][v].add(a)
                            if v == b:
                                dp[ns][u].add(a)
            
            full = size - 1
            ok = False
            for a in range(1, 7):
                if dp[full][a]:
                    ok = True
                    break
            
            if ok:
                ans += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```该代码迭代多米诺骨牌的所有子集。 对于每个子集，它在该子集的掩码上构建压缩的 DP，通过由一个端点和另一个端点的集合索引的嵌套结构隐式跟踪所有可能的端点对。 这可以避免存储具有显式第二端点尺寸的完整 3D 数组。 

初始化将每条边作为具有两个方向的起始链。 如果新边匹配，则转换尝试扩展任一端点。 每次成功的扩展都保留了结构仍然是单链的不变性。 

最后的检查只是验证是否可以通过任何端点配置访问任何完整掩码状态。 

## 工作示例

 ### 示例 1

 输入子集：(1-2)、(2-3)、(3-4)

 我们在制造口罩时跟踪状态。 

| 面膜| 活动链（a → b 组）|
 | ---| ---|
 | 00 | 00 空 |
 | 01 | 1 → {2}, 2 → {1} |
 | 11 | 11 1 → {3}、3 → {1}、2 → {3}、3 → {2} |
 | 111 | 111 1 → {4}、4 → {1}、2 → {4}、4 → {2}、3 → {4}、4 → {3} |

 最后，完整掩码是可达的，因此该子集是有效的。 

此跟踪显示了多个端点配置如何共存，以及 DP 如何自然地探索所有有效的附件顺序而不承诺其中一个。 

### 示例 2

 输入子集：(1-2)、(1-3)、(4-5)

 放置 (1-2) 和 (1-3) 后，端点被限制为 {2,3}。 图块 (4-5) 无法附加到任一端点，因此完整掩码的所有 DP 状态都变为空。 

这说明了跨端点的连接是多么重要，而孤立的组件会立即阻止完成。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(2^N·2^N·N) | O(2^N·2^N·N) | 每个子集在其自己的子集掩码上运行 DP，并在边缘上进行转换 |
 | 空间| O(2^N·6^2) | O(2^N·6^2) | 每个子集掩码的端点跟踪 |

 界限 N ≤ 21 使得 2^N 易于管理。 尽管内部 DP 很重，但大多数状态在实践中是无法到达的，并且端点的小域（1 到 6）保持了转换的界限。 这符合位掩码 DP 问题的典型竞赛约束。

 ## 边缘情况

 关键的边缘情况是所有图块共享一个数字，例如 (1-2)、(1-3)、(1-4)。 在这种情况下，许多子集仍然有效，因为链始终可以围绕 1 旋转。DP 正确地同时保留多个端点状态，因此它永远不会过早地拒绝需要选择不同附件侧的配置。 

另一种边缘情况发生在完全断开的子集（如（1-2）、（3-4））中。 DP 很快达到剩余边缘不存在端点匹配的状态，从而使所有全掩码状态为空。 这反映了这样一个事实：任何排序都无法桥接断开连接的组件。 

最后一个微妙的情况是当图块形成循环时，例如（1-2）、（2-3）、（3-1）。 DP 捕获循环的多个端点旋转，并确认有效性，因为循环始终可以通过选择任何起始边缘并一致延伸来打开。
