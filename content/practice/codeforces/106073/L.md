 ## 解决方案
 ## 问题理解

 我们得到了三个成分：一个单词字典，其中每个单词都有一个固定的二维整数向量，一个充当参考语料库的长文本，以及一组查询。 每个查询都以一个短单词序列结束，我们必须根据模仿简化语言模型的规则来预测下一个单词。 

对于一个查询，我们将其最后 K 个单词作为上下文窗口。 我们扫描整个知识库文本并寻找这K个单词以相同顺序连续出现的每个位置。 每次我们找到这样的匹配项时，我们都会记录紧随该匹配项之后的单词。 这些记录的单词形成了候选的多重集合。 

如果我们找到至少一个候选向量，我们通过对每个字典单词 d 的向量与所有候选向量之间的点积求和来对其进行评分。 字典中不存在的任何候选单词都被视为零向量，这意味着它对任何分数都没有贡献。 然后，我们选择得分最高的字典单词，通过优先选择字典顺序中较早出现的单词来打破平局。 

一个微妙的细节是 K 在实践中对于每个查询并不是固定的。 如果在完整的 K 长度上下文中找不到匹配项，我们会将 K 减一并重试，重复直到找到至少一个匹配项或达到 K = 1。如果即使 K = 1 也没有产生匹配项，则预测失败，我们输出一个星号。 

约束很小：N、M 最多 1000，Q 最多 10。这立即表明我们可以为每个查询和每个减少的 K 重复扫描文本，而不必担心后缀自动机或高级索引结构等渐近优化技巧。 总工作量大约为 Q × K × M，这个值相当小。 

主要的失败案例来自于忘记其中一种行为。 一个常见的错误是在减小 K 时没有重新启动搜索。另一个错误是错误地将未知候选词视为不存在而不是零向量，这巧妙地改变了评分行为，因为它们仍然应该被收集但没有任何贡献。 第三个错误是对打破平局的处理不当，因为字典顺序是唯一的规则，而不是单词的字典顺序。 

## 方法

 直接解决方案准确模拟问题所描述的内容。 

对于每个查询和每个可能的上下文长度 K，我们扫描知识库并检查每个位置以查看接下来的 K 个单词是否与查询后缀匹配。 当找到匹配项时，我们将以下单词记录为候选单词。 扫描后，如果我们至少收集了一个候选向量，我们通过将点积与候选向量相加来计算所有字典单词的分数，并选择最好的一个。 如果不存在候选者，我们递减 K 并重复。 

这种强力方法已经足够了，因为结构是扁平的：知识库只是一个序列，模式很短（K ≤ 5），并且查询数量很少。 最坏的情况涉及每个查询检查最多 K 个值，每次扫描 M 个单词，并进行 O(N) 评分，这仍然在限制范围内。 

关键的观察结果是不需要预处理。 该问题的设计使得重复线性扫描比构建后缀结构更便宜，并且评分步骤是非常小的固定维度（2D 向量）上的线性代数，这使常数保持较低。

 | 暴力模拟 | O(Q·K·M·K + Q·N·K) | O(Q·K·M·K + Q·N·K) | O(N + M) | 已接受 |
 | 优化索引 | 不需要| 不需要| 矫枉过正|

 ## 算法演练

 我们独立处理每个查询。

1. 提取查询的最后 K 个单词。 这些形成了我们试图在知识库中匹配的模式。 
2. 尝试从 K 开始到 1 的当前上下文长度 L。对于每个 L，获取查询的最后 L 个单词并扫描知识库。 
3. 扫描知识库时，检查每个索引 i 以使 i + L 在范围内。 如果words[i : i+L]与上下文完全匹配，则将words[i+L]记录为候选。 
4.完成对固定L的扫描后，如果我们找到至少一个候选者，我们停止减少L并继续评分。 如果不存在候选者，我们将 L 减一并重复。 
5. 如果我们到达 L = 0 而没有找到候选者，我们将输出原始查询，后跟一个星号。 
6. 否则，我们通过迭代所有候选词来计算每个字典单词 d 的分数。 每个候选词贡献其向量和 d 向量之间的点积，除非候选词不在字典中，在这种情况下，其向量被视为 (0, 0) 并且不贡献任何内容。 
7. 我们选择得分最高的字典单词。 如果多个单词并列，我们选择字典索引最小的一个。 

正确性来自于这样一个事实：每个可能的有效上下文事件都会被明确检查，并且评分是固定向量的确定性聚合。 没有近似或启发式，只有穷举匹配和线性累积。 决胜规则纯粹是通过按顺序扫描字典并保留迄今为止看到的最好的来处理的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    idx = {}
    words = []
    vec = []

    for i in range(n):
        parts = input().split()
        w = parts[0]
        x = int(parts[1])
        y = int(parts[2])
        idx[w] = i
        words.append(w)
        vec.append((x, y))

    m = int(input())
    kb = []
    while len(kb) < m:
        kb.extend(input().split())
    kb = kb[:m]

    q, K = map(int, input().split())

    for _ in range(q):
        parts = input().split()
        F = int(parts[0])
        query = parts[1:]

        found_candidates = None
        used_L = 0

        for L in range(K, 0, -1):
            if F < L:
                continue

            pattern = query[F - L:]
            candidates = []

            for i in range(m - L):
                if kb[i:i+L] == pattern:
                    candidates.append(kb[i+L])

            if candidates:
                found_candidates = candidates
                used_L = L
                break

        if not found_candidates:
            print(" ".join(query + ["*"]))
            continue

        scores = [0] * n

        for c in found_candidates:
            if c in idx:
                cx, cy = vec[idx[c]]
                for i in range(n):
                    dx, dy = vec[i]
                    scores[i] += dx * cx + dy * cy

        best = 0
        for i in range(1, n):
            if scores[i] > scores[best]:
                best = i

        print(" ".join(query + [words[best]]))

solve()
```该字典既存储为用于排序的列表，也存储为用于快速向量查找的映射。 知识库被扁平化为一个列表，因此我们可以直接扫描它。 对于每个查询，我们尝试减少上下文长度并通过强力子字符串比较来收集候选者，考虑到较小的约束，这足够有效。 

评分步骤明确地将缺失单词视为零向量，如果它们不在字典映射中，则跳过它们。 

平局决胜自然是通过从左到右扫描索引来处理的，并且仅在发现严格更大的分数时才更新。 

## 工作示例

 考虑一个小场景，字典单词具有简单的向量和短文本。 对于以在知识库中多次出现的短语结尾的查询，我们检查如何收集候选者以及如何累积分数。 

| 步骤| 行动| 候选人|
 | ---| ---| ---|
 | L = K | 扫描完整上下文 | 无 |
 | L = K-1 | 扫描精简上下文 | [“单词A”，“单词B”] |
 | 得分| 点积总和| 选择最好的|

 此跟踪显示了当精确上下文失败但较短上下文成功时的回退机制。 

在存在确切上下文的另一种情况下，我们认为不需要减少。 

| 步骤| 行动| 候选人|
 | ---| ---| ---|
 | L = K | 找到匹配项 | [“x”，“y”，“z”]|
 | 得分| 立即计算分数 | 最终预测|

 这证实了该算法始终优先选择最长的匹配上下文。

 ## 边缘情况

 一种重要的边缘情况是知识库中不存在长度为 K 的子串，但存在较短的子串。 例如，如果 K = 3 但仅存在 K = 2 匹配，则算法必须正确重新启动 L = 2 的扫描，而不是过早中止。 循环结构明确地继续向下确保这种行为。 

另一种情况是候选词不在词典中。 在这种情况下，它仍然参与候选集合，但贡献零向量。 这意味着它根本不应该影响分数，实现通过跳过查找并且不添加任何贡献来确保这一点。 

最后一个边缘情况是打破平局。 如果两个字典单词以相同的分数结尾，则仅应选择较早的字典条目。 这是通过按顺序扫描索引并仅在严格改进时更新来处理的，保留最大分数的第一次出现。
