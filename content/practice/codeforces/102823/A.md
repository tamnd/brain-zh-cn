 ## 解决方案
 ## 问题理解

 我们有两个数组，`A`和`B`。 我们必须通过交错两个数组中的元素来创建一个最终数组，同时保持内部的原始顺序`A`和里面`B`。 合并后，每个元素贡献其值乘以最终数组中从 1 开始的位置。 目标是选择给出尽可能最小总成本的合并顺序。 所需的输出还包括语句所示格式的测试用例编号。 

输入大小排除了尝试所有可能的合并。 如果两个数组有长度`n`和`m`，存在指数级数量的有效交错，因为每次合并对应于选择其中一个数组占据的位置。 长度达到`100000`所有测试的总长度达到`10^6`，任何取决于可能的合并顺序数量的解决方案都是不可能的。 我们需要一种线性时间方法来为每个元素做出一个决定。 

棘手的部分是数组本身不需要排序。 一个常见的错误是始终采用较小的当前元素，因为这类似于正常的合并操作。 这是错误的，因为当我们向右移动时，头寸乘数会增加。 较大的值通常应放置在较早的位置。 

例如，考虑：```
1
2 2
5 3
4 5
```最优合并数组为：```
5 4 5 3
```成本是：```
1*5 + 2*4 + 3*5 + 4*3 = 40
```较小的第一个合并将产生：```
4 5 5 3
```费用：```
1*4 + 2*5 + 3*5 + 4*3 = 41
```差异在于，向左移动较大的数字位置比向左移动较小的数字节省更多。 

另一个边缘情况是相等的值。 例如：```
1
1 1
7
7
```两种可能的合并是相同的：```
7 7
```答案是：```
21
```错误地使用严格比较的解决方案可能会因在值相等时未正确使用其中一个数组而失败。 

最后一种边界情况是一个数组提前完成。 例如：```
1
1 3
8
1 2 3
```选择后`8`首先，其余元素必须按其原始顺序出现：```
8 1 2 3
```答案是：```
8 + 4 + 6 + 9 = 27
```仅在两个数组都有元素时比较元素并忘记剩余后缀的实现将产生不正确的结果。 

## 方法

 直接的暴力解决方案将枚举每个有效的合并。 对于每次合并，它都会计算最终的成本并保持最小值。 这是正确的，因为所有可能的最终安排都会被检查。 然而，合并次数是二项式系数`C(n+m,n)`，呈指数增长。 即使很小的数组也已经创造了很多可能性，因此这种方法无法处理给定的限制。 

关键的观察来自于查看来自不同数组的两个相邻元素。 假设最终数组中的两个相邻元素是`x`其次是`y`。 他们对职位成本的贡献`p`和`p+1`是：```
p*x + (p+1)*y
```如果我们交换它们，贡献就变成：```
p*y + (p+1)*x
```第二种安排更好的是`x < y`。 换句话说，每当来自不同数组的两个可用元素可以交换时，较大的元素应该更早出现。 

在合并的任何时刻，唯一可以立即确定位置的元素是两个数组前面当前未使用的元素。 如果我们选择较小的前部元素，则较大的前部元素将被强制后一位。 交换这两种选择会降低成本。 因此，最佳选择始终是采用两个当前前部元件中较大的一个。 

这与最终的贪心算法使用的推理相同。 蛮力方法探索所有可能的顺序，但交换论证表明，每个最优解决方案都可以转换为每个选择都采用更大的可用前端元素的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(C(n+m,n) * (n+m)) | O(C(n+m,n) * (n+m)) | O(n+m) | 太慢了|
 | 最佳| O(n+m) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从两个数组的第一个未使用元素处的指针开始，并将合并数组中的当前位置设置为`1`。 
2. 当两个数组仍包含未使用的元素时，比较两个当前的前值。 取较大的一个，加上它的贡献`position * value`到答案，并将相应的指针向前移动。 

这种选择之所以安全，是因为前面的两个值是来自不同数组的唯一可以放置在下一个的元素。 如果稍后放置较大的值，则交换两者会降低成本。 
3. 当一个数组变空时，将另一个数组的剩余元素按其原始顺序追加。 它们的相对顺序已经固定，没有进一步的选择。 
4. 继续增加每个放置元素后的位置，直到计算完整个合并数组。 

为什么它有效：

 不变的是，在每个贪婪决策之后，都存在具有完全相同前缀的最佳合并。 考虑两个可用的前端元件`x`和`y`。 如果最佳合并将较小的元素放在较大的元素之前，则这两个元素最终将按该顺序出现，因为它们自己的数组中的元素都不能交叉。 交换两个相邻的选择会通过将较大的值向左移动一个位置来改变成本，但这永远不会增加答案。 重复这种交换可以消除所有这样的错误选择，因此采用较大的当前元素始终可以保持最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(a, b):
    i = 0
    j = 0
    pos = 1
    ans = 0
    n = len(a)
    m = len(b)

    while i < n and j < m:
        if a[i] >= b[j]:
            ans += pos * a[i]
            i += 1
        else:
            ans += pos * b[j]
            j += 1
        pos += 1

    while i < n:
        ans += pos * a[i]
        i += 1
        pos += 1

    while j < m:
        ans += pos * b[j]
        j += 1
        pos += 1

    return ans

def main():
    t = int(input())
    out = []

    for case in range(1, t + 1):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        out.append(f"Case {case}: {solve_case(a, b)}")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```两个指针`i`和`j`表示两个原始数组中的下一个可用元素。 主循环完全执行演练中描述的贪婪决策。 比较使用`>=`而不是`>`以便一致地消耗相同的值而不影响答案。 

当一个数组用完后，剩下的循环就不再可选了。 其余元素仍然会增加成本，并且它们的位置从第一个循环停止的点开始继续增加。 

Python 整数会自动以任意精度使用，这很有用，因为最大可能的成本可能会超过 32 位整数限制。

 ## 边缘情况

 对于相等的值，例如：```
1
1 1
7
7
```该算法比较`7`和`7`，选择第一个数组，因为`>=`条件，然后取剩余元素。 顺序并不重要，因为两个贡献是相同的。 

对于一个数组提前完成的情况：```
1
1 3
8
1 2 3
```该算法首先比较`8`和`1`, 需要`8`，然后第一个数组为空。 剩余值`1,2,3`必须按顺序出现，给出：```
8 1 2 3
```有成本`27`。 

对于所有相等的值：```
1
3 3
0 0 0
0 0 0
```每个可能的合并成本为零。 贪婪决策仍然只消耗每个元素一次并返回正确的结果。 

对于选择较小元素看起来很诱人的值：```
1
2 2
5 3
4 5
```该算法首先选择`5`超过`4`。 该选择就是创建最佳前缀的原因，因为稍后放置较大的值会增加其乘数，同时减少较小值的乘数。 最终结果是`40`。
