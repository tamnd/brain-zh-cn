 ## 解决方案
 ## 问题理解

 这个问题给我们带来了一种类似 Hanabi 的纸牌游戏，其中 Zuko 将所有纸牌放在一行中，每种牌代表等级和颜色的组合。 Iroh 可以看到牌，但 Zuko 看不到。 轮到 Iroh 时，他通过突出显示特定等级的所有牌或特定颜色的所有牌来提供线索。 然后 Zuko 将打出最左边突出显示的牌。 游戏会在线索之间交替进行，直到所有卡牌都按照每种颜色的等级按照正确的顺序打出。 打出一张等级牌$r \ge 2$在相同颜色的上一个排名之前已经玩过是非法的。 

目标是设计线索的顺序，以便所有牌都合法打出，同时最大限度地减少 Iroh 的线索与上一回合相比发生变化的次数。 

输入由多个测试用例组成。 每个测试用例给出$n$等级和$m$颜色，然后是列表$n \cdot m$卡片出现在 Zuko 手中时的等级和颜色。 输出是整个游戏中线索变化的最小次数。 

约束允许最多$2 \cdot 10^5$所有测试用例的总卡数。 这意味着算法具有超过$O(n \cdot m)$复杂性会太慢，并且二次方法是不可行的。 

一个简单的边缘情况是同一等级的所有卡牌连续出现。 例如，如果手中的所有 1 级牌都已经是连续的，则无需更改线索即可按顺序打出所有牌。 如果不小心，每回合都会改变线索，就会过度计算变化并产生错误的答案。 

## 方法

 暴力方法会尝试模拟游戏，在每个回合发出所有可能的线索，跟踪 Zuko 的游戏顺序，并计算线索变化。 这在原则上是正确的，但需要在每个回合检查每张牌和潜在的线索。 高达$2 \cdot 10^5$卡，操作数量将爆炸至$O((n \cdot m)^2)$，这是不可行的。 

关键的见解来自于注意到比赛顺序必须遵循每种颜色内递增的排名。 这意味着我们可以将手视为颜色等级递增的一系列“块”。 如果我们跟踪某个颜色的上一个排名的最新位置，我们就可以确定 Iroh 必须切换线索的最小移动次数。 具体来说，问题简化为在按递增顺序遍历手时找到单调线段的最小数量。 我们可以为每张卡的每种颜色分配一个“排名顺序索引”，然后计算该索引序列减少了多少次。 每次减少对应于所需的线索变化。 这将问题转化为$O(n \cdot m)$序列处理任务。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O((n*m)^2) | O((n*m)^2) | O(n*m) | 太慢了|
 | 排名顺序 | O(n*m) | O(n*m) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，请阅读$n$,$m$以及手作为排名和颜色的列表。 
2. 构造一个字典，将每种颜色映射到排名位置列表$1$到$n$。 这使我们能够确定颜色中每个等级的播放顺序。 
3. 对于每种颜色，为每张卡分配一个“递增排名顺序的位置”索引，即排名 1 的卡为 1，排名 2 的卡为 2，依此类推。 
4. 将手中的每张牌替换为颜色序列中相应的索引。 这将问题转化为计算这个新数组中严格递增序列的最小数量。 
5. 从左向右移动变换后的手。 维护每种颜色的最后一个索引值。 每当当前卡牌的索引小于或等于最后一张相同颜色的卡牌时，就增加所需线索变化的计数。 这抓住了 Iroh 必须切换线索以确保 Zuko 正确演奏的关键点。 
6. 输出测试用例的线索变化总数。 

这里的不变性是，在每种颜色内，手牌中的等级索引序列必须是非递减的，以避免非法玩法。 计算减少的数量可以准确地给出维持合法性同时最小化更改所需的线索更改数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        ranks = list(map(int, input().split()))
        colors = list(map(int, input().split()))
        pos_in_color = [[] for _ in range(m + 1)]
        
        for i in range(n * m):
            pos_in_color[colors[i]].append((ranks[i], i))
        
        index_in_color = [0] * (n * m)
        for c in range(1, m + 1):
            # Sort by rank to get correct play order
            pos_in_color[c].sort()
            for order, (_, idx) in enumerate(pos_in_color[c]):
                index_in_color[idx] = order + 1
        
        res = 0
        last = 0
        for i in range(1, n * m):
            if index_in_color[i] < index_in_color[i - 1]:
                res += 1
        print(res)

solve()
```在此代码中，我们首先构建按等级排序的每种颜色的卡片列表。 然后我们用颜色序列中的顺序替换每张卡片。 最后，遍历手数按顺序递减，每手数都代表一次必要的线索变化。 

微妙之处包括基于一的索引与基于零的排序顺序的索引以及仔细跟踪递减而不是相等，因为非递减序列在没有线索变化的情况下是可以接受的。
