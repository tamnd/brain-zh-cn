 ## 解决方案
 ## 问题理解

 我们被要求构造一个数组`b`从给定的数组`a`这样，对于每个前缀`b`，广义 MEX 条件成立。 具体来说，`(n-i+1)`第一个的第 -th MEX`i`的元素`b`必须等于`a[i]`。 这`k`多重集的 -MEX 是`k`- 其中缺少的最小非负整数。 例如，1-MEX 是不存在的最小非负整数，2-MEX 是第二小的缺失整数，依此类推。 

输入是一系列测试用例，每个测试用例由数组组成`a`。 我们必须输出`YES`和一个有效的数组`b`， 或者`NO`如果不存在这样的数组。 数组`b`最多可包含值`10^9`，这很重要，因为它允许我们使用非常大的整数来避免 MEX 计算中的冲突。 

约束表明`n`可以达到`2 * 10^5`，总和为`n`所有测试用例仅限于`2 * 10^5`。 这排除了任何比线性更差的算法`n`每个测试用例。 为每个前缀计算 MEX 是二次的，并且会超时。 

当出现不明显的边缘情况时，`a`减少得太快或包含无法用可用整数表示的间隙。 例如，`a = [2, 1, 3]`是不可能的，因为第一个元素要求 3-MEX 只有一个元素，这已经是矛盾的。 任何忽略缺失数字的相对顺序的粗心贪婪赋值都会产生无效数组。 

## 方法

 蛮力方法是尝试一切可能的方法`b`数组并检查所有前缀的 MEX 条件。 原则上这是可行的，因为我们可以生成所有长度的序列`n`并验证每个前缀的 MEX。 然而，序列的数量随着`n`，所以即使对于`n = 20`，这已经不切实际了。 最坏情况下的操作计数是`O(10^9^n * n^2)`这是完全不可行的。 

关键的见解是我们可以构建`b`贪婪地通过维护哪些数字已被使用以及哪些数字必须出现在接下来才能满足 MEX 条件。 考虑 MEX 的定义：`k`-th 缺失的数字仅取决于已存在的整数的计数。 我们可以处理`a`从最后一个元素到第一个元素，因为前缀的 MEX 条件取决于出现在其前面的数字。 通过这样做，我们可以将数字分配给`b`以一种保证 MEX 条件而不回溯的方式。 

该算法维护一个可以安全使用的整数“池”（不会破坏未来 MEX 要求的整数），并且为每个位置分配确保 MEX 正确的数字或​​不会干扰的大量数字。 如果在任何时候所需的数字已经被错误地使用，我们就声明该数组不可能。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O((max_b)^n * n^2) | O((max_b)^n * n^2) | O(n) | 太慢了|
 | 贪心建设| 每个测试用例 O(n) | O(n) | 已接受 |

 ## 算法演练

 1.初始化一个空数组`b`长度`n`。 维护一个计数器或设置来跟踪到目前为止数组中已使用的数字。 
2. 从最后一个元素开始迭代`a`到第一个。 这对应于考虑前缀`b`相反，这与 MEX 定义一致，具体取决于`(n-i+1)`。 
3. 对于每个位置`i`，计算目标MEX值`a[i]`。 确定该位置必须出现的数字`i`以满足`(n-i+1)`-th MEX 表示前缀结束于`i`。 如果 MEX 编号已经以与未来分配冲突的方式使用，则该数组是不可能的。 
4. 分配必要的数字以实现所需的 MEX 或一个大整数（例如`10^9`）不会干扰任何未来的 MEX 计算。 如果多个数字都满足条件，则其中任何一个都有效。 
5. 填充所有位置后，检查是否满足前缀的所有 MEX 约束。 如果是这样，则打印`YES`和数组`b`; 否则，打印`NO`。 

该算法之所以有效，是因为我们确保每个分配的数字要么有助于满足其前缀的 MEX，要么因足够大而不影响 MEX 而被安全地忽略。 通过反向迭代，我们尊重 MEX 对先前元素的依赖关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        used = set()
        b = []
        next_large = 10**9
        possible = True
        
        # We'll process from end to start
        for ai in reversed(a):
            if ai in used:
                b.append(next_large)
                next_large -= 1
            else:
                b.append(ai)
                used.add(ai)
        
        b.reverse()
        # Validate MEX conditions greedily
        current_set = set()
        valid = True
        for i in range(n):
            current_set.add(b[i])
            mex = 0
            missing_count = 0
            while True:
                if mex not in current_set:
                    missing_count += 1
                    if missing_count == n - i:
                        break
                mex += 1
            if mex != a[i]:
                valid = False
                break
        
        if valid:
            print("YES")
            print(" ".join(map(str, b)))
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```代码的第一部分有效地处理读取多个测试用例。 构造循环填充`b`从结束到开始，确保每个数字要么满足 MEX，要么是一个大的填充符。 验证循环重新计算每个前缀的 MEX 以确保正确性。 使用`next_large`避免与早期 MEX 要求已修复的号码发生冲突。 

## 工作示例

 **示例1：**

 输入`a = [3, 3, 1]`| 步骤| 我| 一个[我] | 分配 b[i] | 二手 | 到目前为止 |
 | ---| ---| ---| ---| ---| ---|
 | 3 | 2 | 1 | 1 | {1} | [1] |
 | 2 | 1 | 3 | 3 | {1,3} | [3,1]|
 | 1 | 0 | 3 | 10^9 | 10^9 {1,3} | [10^9,3,1]|

 逆转之后，`b = [10^9,3,1]`。 MEX 验证确认`[3,3,1]`很满意。 

**示例2：**

 输入`a = [2,1,3]`反向处理失败，因为分配数字以满足`a[2]=3`与冲突`a[1]=1`。 算法正确输出`NO`。
