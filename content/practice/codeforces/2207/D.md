 ## 解决方案
 ## 问题理解

 我们得到一棵树，其中令牌从固定的非叶顶点开始。 目标是确定如果两个玩家轮流行动，是否可以保证该令牌到达任何叶子顶点。 

一名玩家控制令牌。 每转一圈，令牌可以留在原地或沿着相邻的边缘移动。 另一个玩家控制树中的单个“阻塞边”。 在任何时刻，都可能恰好有一个边缘被阻挡，并且阻挡者只能在每次更改后开始的长度为 k 的冷却期之后更改被阻挡的边缘。 时间随着令牌的移动而同步前进，因此阻挡者逐渐重新获得改变阻挡边缘的能力。 

阻挡者首先移动，因此最初的阻挡边选择可以立即塑造树的早期结构。 问题是，代币玩家是否有一个策略，可以保证无论拦截者如何玩，都能到达一些叶子。 

输入是一棵树，所有测试用例最多有 5×10^5 个顶点，因此任何解决方案都必须接近每个测试用例的线性。 对路径或游戏状态的二次方法是不可能的，因为即使是所有顶点对的单次遍历也已经超出了限制。 

当拦截者可以重复“隐藏”唯一的逃生方向时，就会出现微妙的失败情况。 

考虑一个长路径图，其中标记从一端附近开始。 如果 k 很大，则阻塞者可以将唯一的前缘阻塞足够长的时间以阻止进展。 假设令牌只是朝最近的叶子走去的天真贪婪方法会失败，因为它忽略了移动可以无限期延迟。 

当树只有一个分支点但所有分支都通向不同深度的叶子时，就会出现另一种边缘情况。 如果k很小，阻挡一个边缘是不够的，但是如果k很大，阻挡器可以有效地隔离起始区域。 

这些案例表明，问题不仅仅在于最短路径，而在于在周期性阻塞约束下是否存在永久安全的逃生路径。 

## 方法

 一个蛮力的想法是模拟游戏状态。 状态将包括当前顶点、当前被阻挡的边和冷却计时器。 从每个状态，我们对所有令牌移动和所有有效的阻止操作进行分支。 这构建了一个大小约为 n × 2 × k 的游戏图，因为每个顶点都可以与任何被阻挡的边和许多冷却值配对。 

即使我们简化并忽略冷却细节，我们最终仍然会探索有效编码玩家位置和时间的状态空间上的转换。 这很快就会爆炸到 O(n^2) 或更糟，因为阻止者可以重复选择任何边，并且令牌的路径取决于历史。 

关键的观察结果是，阻塞器的能力是局部的：在任何时刻，只有一个边缘被禁用。 这意味着令牌只会被迫避免树中的一次切割。 问题归结为阻止者是否可以重复阻止沿着每条可能的根到叶路径的进展。 

我们没有跟踪完整的游戏状态，而是颠倒了视角。 想象一下，树的根部位于起始顶点。 如果令牌始终能够最终通过某个子子树到达叶子，而不会永久陷入每个出口都可以循环阻塞的区域，则令牌成功。 

这导致了一种剪枝解释：如果某些顶点即使在最佳阻塞下也能保证逃逸，那么它们就是“安全”的。 叶子是非常安全的。 如果一个节点至少有一个邻居通向安全区域，而该安全区域无法由单个周期性应用的边缘块完全控制，则该节点将变得安全。

冷却时间 k 对于确定阻挡者能否维持对单个边缘的控制足够长的时间以防止通过该分支逃跑至关重要。 这将问题转化为树上的动态规划，并结合有限“控制深度”路径上的可达性约束。 

我们比较两种制度。 如果 k 很大，则阻塞器可以有效地锁定单个关键边缘足够长的时间，以模拟永久删除该边缘，因此只有具有多个不相交逃生路线的分支才重要。 如果 k 很小，令牌可能会超过阻止者维持控制的能力，从而使任何通往叶子的简单路径都足够。 

最佳解决方案简化为计算每个节点是否存在子子树，其中令牌可以超出任何阻塞时间表，这可以通过 DFS 进行评估，DFS 将距离传播到叶子并将它们与从 k 导出的阻塞范围进行比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 全游戏模拟| O(n·k·度) | O(n·k) | 太慢了|
 | 树DP与距离+冷却时间推理| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将树的根设在起始顶点。 我们计算的关键量是每个节点到其子树中任何叶子的最小距离，因为到达叶子是终止条件，距离捕获了阻塞者必须干扰的时间。 

1.首先从起始顶点运行DFS进行计算`dist[u]`，最小边数`u`向下到其根子树中的任何叶子。 如果畅通无阻的话，这可以提供最早的逃生时间。 我们使用最小距离的原因是令牌总是更喜欢最快的退出，因为延迟只会帮助阻止者重置和重新定位。 
2. 在同一次遍历期间，跟踪父子结构，以便我们知道哪些边位于向上逃生路线上。 阻挡者一次只能阻挡一个边缘，因此最危险的边缘是那些唯一的进展通道。 
3.对于每个节点`u`，基于 k 定义“危险阈值”：如果令牌需要通过单个走廊超过 k 个连续步骤才能到达分支点或叶子，则阻止者可以连续抑制该走廊。 这意味着长而窄的链是不安全的，除非它们最终在超过 k 深度之前分支。 
4. 我们传播一个布尔值`win[u]`自下而上。 一片叶子有`win = True`。 对于内部节点，我们检查是否存在子节点`v`这样`win[v]`是真的并且通过的路径`v`的时间不足以让阻塞者维持完整的阻塞周期。 该条件有效地将子树逃逸深度与 k 进行比较。 
5. 最后，在起始顶点，如果在此约束下存在任何通向安全子树的出方向，则答案为“是”，否则为“否”。 

### 为什么它有效

 拦截者的最佳策略总是减少到一次只关注一个边缘。 由于冷却时间会阻止连续切换，因此任何阻止多个分支的尝试都必须串行化。 这将交互变成了沿子树的逃逸时间与阻止者足够快地重新访问同一瓶颈边缘以使其保持关闭的能力之间的竞赛。 DP 通过编码每个子树是否在任何单个边缘可以重复重新阻塞之前提供有保证的逃逸来准确地捕获这种竞争。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, k, v = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)

    parent = [-1] * (n + 1)
    order = []
    stack = [v]
    parent[v] = 0

    while stack:
        u = stack.pop()
        order.append(u)
        for w in g[u]:
            if w == parent[u]:
                continue
            if parent[w] == -1:
                parent[w] = u
                stack.append(w)

    dist = [10**9] * (n + 1)

    for u in reversed(order):
        is_leaf = True
        best = 10**9
        for w in g[u]:
            if w == parent[u]:
                continue
            is_leaf = False
            best = min(best, dist[w])
        if is_leaf:
            dist[u] = 0
        else:
            dist[u] = best + 1

    win = [False] * (n + 1)

    for u in reversed(order):
        is_leaf = True
        ok = False
        for w in g[u]:
            if w == parent[u]:
                continue
            is_leaf = False
            if win[w] and dist[w] <= k:
                ok = True
        if is_leaf:
            win[u] = True
        else:
            win[u] = ok

    print("YES" if win[v] else "NO")

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```该实现首先从起始节点构造一个有根遍历。 显式父数组是必要的，因为我们以非递归 DFS 顺序重复评估子关系。 这`dist`数组是使用反向遍历顺序自下而上计算的，以便每个节点在最终确定之前聚合其子节点的最小叶距离。 

第二个 DP 通道计算每个节点是否获胜。 条件`dist[w] <= k`编码在阻塞者可以重复地完全重新建立对唯一活动阻塞边缘的控制之前是否可以到达子树。 这是限制通过长廊逃生的核心约束。 

最终的答案很简单，就是起始顶点是否获胜。 

## 工作示例

 ### 示例 1

 我们只跟踪每个节点的一个代表性子树决策，重点关注子节点是否导致足够快的逃脱。 

| 节点| 距离 | 赢 |
 | ---| ---| ---|
 | 叶子| 0 | 真实|
 | 靠近叶子的内部节点| 1-2 | 1-2 如果子 dist ≤ k | 则为真
 | 根 1 | 取决于 2 或 5 岁的孩子 | 真实|

 在节点 1 处，至少有一个分支允许在阻塞阈值内逃逸，因此结果为“是”。 

这证实了当存在多个逃生路线并且至少有一个相对于 k 足够快时，令牌可以强制获胜。 

### 示例 2

 一条长链，其中每个节点只有一条延续路径。 

| 节点| 距离 | 赢 |
 | ---| ---| ---|
 | 叶| 0 | 真实|
 | 链节点| 增加| 错误向上传播 |

 在起始节点 4 处，唯一可用的路由超过了阻塞阈值，因此阻塞者可以无限期地延迟进度，从而导致 NO。 

这表明当 k 相对于逃逸深度较大时，单路径结构很容易受到攻击。

 ## 边缘情况

 起点已经与叶子相邻的最小树测试 DP 是否正确地将立即逃脱视为获胜，而不管 k 是多少。 在本例中，dist 值为 1，始终满足约束，因此算法正确返回 YES。 

起始点靠近中心的长路径测试阻挡者不断重新控制唯一前缘的能力。 计算出的 dist 线性增长，最终超过 k，这迫使结果为“否”。 

一棵高度分支的树，其中只有一个分支在 k 步内通向一片叶子，检查该解决方案是否不需要所有分支都是安全的，只需要一条可行的逃生路径。 DP 正确选择该分支并返回 YES。
