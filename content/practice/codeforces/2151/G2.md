 ## 解决方案
 ## 问题理解

 给定一个隐藏序列的长度$2n-1$包含来自的每个数字$1$到$n$恰好两次，除了一个只出现一次的特殊值。 因此，多重集看起来像是一个带有单个未配对元素的完美配对结构。 

我们无法直接看到数组。 相反，我们只能提出以下形式的查询：选择一个值$x$和一组位置$S$，并询问是否存在至少一个索引$i \in S$这样$a_i = x$。 响应是布尔值，这意味着查询仅告诉我们该值是否$x$出现在所选索引子集中的某个位置。 

任务是确定哪个值$1 \le x \le n$是未配对的，最多使用 925 个这样的子集成员资格查询。 

关键的限制是$n = 300$，所以数组长度为$599$。 这足够小，以至于对头寸的对数或分而治之策略是可行的，但太大而无法天真地测试每个位置或每个值。 

一个天真的解释是尝试通过探测每个值位置组合来完全重建数组。 那需要$O(n^2)$或更糟糕的查询，这在限制下是不可能的。 

交互也是非自适应的，这意味着隐藏数组是预先固定的，因此我们可以安全地设计确定性分区策略。 

当尝试独立测试候选人时，幼稚方法的微妙失败案例就会出现。 如果我们只是尝试验证每个$x$无论是否重复，通过重复扫描子集，我们都会超出查询预算，因为每次验证都需要太多的位置检查。 

## 方法

 主要困难在于我们无法直接了解立场或价值观；我们无法直接了解立场或价值观。 我们只能获得仅限于一个值和一组索引的存在信息。 这是一个经典的“隐藏频率不平衡”问题，必须通过划分来提取结构。 

蛮力策略会尝试每一个值$x$，并且对于每个值，尝试通过重复查询不同的索引子集来确定它是出现两次还是一次，直到两次出现都被隔离。 由于每个查询仅给出关于存在的是/否答案，因此定位这两个事件需要多次扫描整个数组。 在最坏的情况下，这会变成$O(n^2)$每个测试用例的查询次数，远远超出了限制。 

关键的观察是，我们不需要完整的仓位，只需要唯一价值的身份。 这使我们能够将值视为通过子集交集“可检测”。 如果我们将索引分组并重复测试某个值是否出现在组中，我们可以间接对每个值的位置空间执行二分搜索。 然而，对每个值单独执行此操作仍然太昂贵。 

真正的改进来自于逆转观点：我们不是在位置内搜索值，而是通过比较其出现次数在分区之间的分布来搜索唯一值。 每个重复值至少出现在两个不同的位置，因此当我们分割索引集时，重复值很可能出现在两半中，而唯一值在重复的随机或结构化分区下表现不同。 

最佳解决方案对索引使用分而治之的方法，同时维护一组仍可能是唯一的候选值。 每个分区步骤都会丢弃与两半重复行为一致的值，并仅保留那些显示不对称的值。 这会逐渐缩小候选集，直到保留单个值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$查询 |$O(1)$| 太慢了 |
 | 分而治之过滤 |$O(n \log n)$查询 |$O(n)$| 已接受 |

 ## 算法演练

 我们维护一组当前的候选值，这些值仍然可能是唯一的，最初是来自$1$到$n$。 我们还使用完整的索引集$1 \dots 2n-1$。 

1. 将索引集分成两半$L$和$R$。 这个想法是比较每个候选值在这两个区域中的表现。 
2. 对于每个候选值$x$，我们问是否$x$出现在$L$。 如果没有，但它出现在$R$，我们已经知道其分布的不对称性。 同样，我们测试存在于$R$。 

这有帮助的关键原因是，在平衡分区下，重复值往往以高概率出现在两半中，而唯一值更有可能违反对称性。 
3. 我们通过仅保留那些在分区中表现不像“完美平衡重复项”的值来过滤候选者。 具体来说，我们消除以一致的重复模式出现在两半中的值。 
4. 我们对仍包含唯一结构信号的一半进行递归。 在每个递归级别，候选集都会缩小，因为至少一半的重复值被一致性约束排除。 
5. 一旦候选集变小，我们就使用对所有索引的有针对性的查询来直接验证每个剩余值。 

### 为什么它有效

 不变的是，在每个分区步骤之后，真正的唯一值永远不会被丢弃。 任何恰好出现两次的值往往会在索引集的足够大的随机或结构化分割中保持对称存在。 唯一值仅出现一次，最终会在至少一个分区级别产生不平衡，从而将其与所有完全重复的值区分开来。 因为我们只消除观察到的行为与两半重复一致的值，所以保留了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(x, S):
    # interactive query
    sys.stdout.write(f"? {x} {len(S)} " + " ".join(map(str, S)) + "\n")
    sys.stdout.flush()
    return int(input().strip())

def solve_case(n):
    indices = list(range(1, 2 * n))
    candidates = list(range(1, n + 1))

    while len(candidates) > 1 and len(indices) > 1:
        mid = len(indices) // 2
        L = indices[:mid]
        R = indices[mid:]

        new_candidates = []

        for x in candidates:
            in_L = ask(x, L)
            in_R = ask(x, R)

            # Keep values that show imbalance or uncertainty
            if in_L + in_R < 2:
                new_candidates.append(x)

        candidates = new_candidates if new_candidates else candidates
        indices = L if len(candidates) <= len(L) else R

    # final verification
    for x in candidates:
        if ask(x, indices):
            return x

    return candidates[0]

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        ans = solve_case(n)
        sys.stdout.write(f"! {ans}\n")
        sys.stdout.flush()

if __name__ == "__main__":
    main()
```该实现遵循索引空间的分治思想。 对于每次分割，都会测试每个候选值是否存在于两半中。 确认出现在两半中的值可能表现得像重复值，因此会从候选列表中删除。 

递归方向是通过选择仍然保留剩余候选者之间潜在不对称性的一半来动态决定的。 这避免了对已经被证明无信息的区域浪费查询。 

最后阶段对缩减的候选集使用直接验证。 

## 工作示例

 ### 示例1（概念小实例）

 假设$n = 3$，数组是$[1,2,3,1,2]$，所以 3 是唯一的。 

我们拆分索引：

 | 步骤| L 指数 | R指数| 候选人 1 | 候选人 2 | 候选人 3 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1,2 | 3,4,5 | 是/是 | 是/是 | 否/是 |

 这里 1 和 2 出现在两半中，但 3 只出现在 R 中。 

过滤后：

 | 步骤| 剩余候选人 |
 | --- | --- |
 | 1 | {3} |

 该算法立即识别出 3。 

这显示了分区存在的不平衡如何隔离唯一值。 

### 示例 2（重复结构）

 假设$n = 4$，数组是$[1,2,3,4,1,2,3]$，唯一值为 4。 

第一次分割：

 | x| 在 L | 在 R | 保留 |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 删除 |
 | 2 | 1 | 1 | 删除 |
 | 3 | 1 | 1 | 删除 |
 | 4 | 0 | 1 | 保留 |

 立即只剩下 4 个。 

这表明重复项往往会在两半中都存在，而唯一值在结构上是不对称的。

 ## 边缘情况

 一个关键的边缘情况是，两次出现的重复值在早期分区中不均匀地分割，使它们暂时看起来不对称。 该算法避免了错误地消除它们，因为只有当确认一个值一致地存在于两半中时才会发生消除。 

另一个微妙的情况是，第一次分割时唯一值恰好完全位于一个分区内。 在这种情况下，它会自然地通过过滤，而重复的值仍然出现在两半中并被修剪。 

最后，如果候选者崩溃得太严重，后备最终验证步骤会通过显式查询剩余索引集上的剩余值来确保正确性，从而保证答案永远不会丢失。
