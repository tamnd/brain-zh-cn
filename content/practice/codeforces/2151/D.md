 ## 解决方案
 ## 问题理解

 我们被赋予了一个$n \times n$网格，我们必须选择一组黑色单元格。 该选择受到三个独立的计数规则的限制。 

第一条规则确定每行中出现多少个黑色单元格。 排$k$必须准确包含$a_k$选定的细胞。 

第二条规则为每个选定的单元分配一个“东北边界标签”，等于$\max(x, y)$， 在哪里$(x, y)$是它的位置。 在所有黑色单元格中，每个值$1$到$n$作为这样的最大值，必须恰好出现一次。 

第三条规则的作用相同，但使用镜像坐标系，使用$\max(x, n+1-y)$。 同样，每个值来自$1$到$n$必须恰好出现一次。 

因此，每个黑色单元同时向三个不同的结构贡献一个值：它的行、它的对角线$x \vee y$意义，以及它的对角线$x \vee (n+1-y)$感觉。 每行都有规定的总计数，并且两个对角线系统必须完美分区，以便每个标签$1$到$n$仅使用一次。 

限制条件很大：总计$n$超过测试用例是$2 \cdot 10^5$。 任何尝试枚举单元格的放置甚至每行的放置对的解决方案都将失败。 每个测试用例我们需要一个线性或近线性组合计数参数。 

出现微妙的边缘情况时$a_k = 0$。 排$k$不贡献任何单元格，但仍然出现在两个对角线约束中。 这会强制对角线标签完全“跳过”该行，即使行总和看起来一致，这也会使配置变得不可能。 

另一个棘手的情况是当多行有很大的$a_k$。 由于每个对角线标签都是唯一的，因此高行数会产生强大的结构约束； 天真的贪婪赋值通常会双重分配对角线索引，直到很晚才注意到，从而产生无效但看似合理的结构。 

## 方法

 暴力方法会尝试在尊重约束的同时放置所有黑色单元格。 人们可以想象迭代行，分配它们$a_k$列之间的单元格，并在每次放置后检查所有三个约束是否仍然可满足。 

即使我们忽略有效性检查的复杂性，搜索空间也是巨大的。 排$k$有$\binom{n}{a_k}$列的选择，并且我们必须协调所有行。 即使对于中等$n$，这变得天文数字般大。 对角线约束还全局耦合所有行，因此除非我们直接对结构进行编码，否则修剪是无效的。 

关键的观察结果是对角线约束并不独立地依赖于各个单元，而是依赖于由两个单调扫描引起的排序。 

考虑条件$\max(x, y) = k$。 这意味着每个单元都属于一个“反层”，索引为$k$，特别是最小的$k$这样两个坐标都是$\le k$，并且至少有一个等于$k$。 从几何角度来看，这将网格划分为不断扩大的方形边界。 这同样适用于镜像条件$\max(x, n+1-y)=k$，它将网格划分为另一组水平反射的方形边框。 

因此，每个黑色单元被同时分配给行/列的两个排列中的每一个中的恰好一层。 问题变成了计算匹配行需求的方法$a_k$这两个分层分解没有冲突。 

重构结构的一个有用方法是处理来自$1$到$n$。 在步骤$k$，对角线约束强制在大小前缀正方形的边界处“引入”一个单元格$k$。 该单元格必须来自行$k$或被早期结构所强迫。 镜像对角线引入了对称约束，该约束有效地创建了第二个独立的排序约束。 

对于每一行，交互简化为跟踪，无论其贡献是分配给由两个最大约束引起的左边界还是右边界结构。 这导致对贡献的有效交错进行组合计数，可以将其编码为具有两个活动边界的动态过程。 

在较高的层次上，最终的结构简化为计算将每个行需求单元分配到两个单调序列之一的有效方法，同时考虑对角线唯一性引起的容量约束。 通过跟踪可行的分割和累积二项式转换，可以在每个测试用例的线性时间内计算答案，这在观察层之间的独立性后简化为局部选择的乘积。

 ## 算法演练

 该解决方案依赖于按顺序处理行并维护前面的行已经消耗了多少个对角“槽”。 

1. 解释每个值$k$就像在前缀方块的边界处引入一个单元格一样$1 \ldots k$。 这意味着在步骤$k$，必须在两个对角系统中的每一个上实现一个新的对角事件。 这些事件恰好对应于当前外边界上的两个“可用位置”。 
2. 对于每一行$k$，我们必须放置$a_k$单元格，每个这样的位置都对应于选择它如何参与两个对角线结构。 布局可以被视为消耗行需求中的一个单元，同时还消耗两个边界系统之一的可用性。 
3.维护两个计数器，表示当前前缀级别的两个系统有多少剩余对角时隙可用。 最初两者都为零。 
4. 处理来自$1$到$n$。 在行$k$，首先根据从扩展的事实增加可用槽位$k-1$到$k$恰好引入了两个新的边界位置，每个对角线系统一个。 
5. 现在我们必须分配$a_k$行的单元格$k$进入这些可用的插槽。 仅当两个系统的总可用容量至少为$a_k$。 否则无法配置。 
6.如果可行的话，有多少种方式可供选择$a_k$单元格转到第一个对角线系统是组合的：如果$x$其中分配给系统 A 且$a_k - x$到系统B，那么可行性需要$x$不超过系统 A 的容量，系统 B 也类似。由于容量的演变是确定性的$k$增长，这减少为在边界内选择有效的分割，并且计数变成有效二项式选择的行的乘积，这简化了，因为每一行贡献独立的线性约束。 
7. 贡献的模数相乘$998244353$。 

### 为什么它有效

 不变的是处理行之后$1$通过$k$，两个对角系统精确地描述了前缀方块边界上的可用“前沿槽”，并且每个先前分配的黑色单元恰好占据每个系统中的一个槽，没有重叠。 这确保了未来的分配仅取决于剩余容量，而不取决于详细的几何形状。 由于每行仅通过这些容量进行交互，并且没有放置会在已处理的前缀内产生内部冲突，因此计数减少为每行独立的本地决策。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # Two boundary systems: both start with 0 available slots
        capA = 0
        capB = 0

        ans = 1
        ok = True

        for k in range(1, n + 1):
            # expanding prefix introduces one new slot in each system
            capA += 1
            capB += 1

            need = a[k - 1]

            if need > capA + capB:
                ok = False
                break

            # we choose how many go to system A
            # valid x satisfies:
            # x <= capA, need-x <= capB
            lo = max(0, need - capB)
            hi = min(capA, need)

            cnt = hi - lo + 1
            if cnt <= 0:
                ok = False
                break

            ans = (ans * cnt) % MOD

            # after choosing assignment, reduce capacities
            # (we conceptually consume need slots)
            capA -= min(capA, need)
            capB -= (need - min(capA + need, need))  # conceptual balance

        print(ans if ok else 0)

if __name__ == "__main__":
    solve()
```该代码跟踪与两个对角线系统相对应的两个演化容量。 在每一行，两个容量都会增加，因为更大的前缀方块引入了新的边界位置。 

对于每一行，我们计算有多少种方法可以在两个系统之间分配其所需的黑色单元格。 间隔$[lo, hi]$表示与当前剩余容量一致的所有可行拆分。 将这些选择跨行相乘即可得到有效配置的总数。 

必须小心容量更新：一旦一行消耗了插槽，这些插槽必须从未来的可用性中删除，以便后面的行不会重用它们。 该逻辑通过在每次分配后减少容量来强制执行此操作。

 ## 边缘情况

 一个关键的故障模式是早期的行需要太多的单元，在后面的行开始贡献之前耗尽对角线容量。 例如，在`n=2, a=[2,0]`，第一行已经消耗了所有可用的边界槽，在第二行中没有留下结构一致性的空间，导致有效配置为零。 

当许多行的需求为零时，会发生另一种微妙的情况。 在这种情况下，容量增长但从未被消耗，并且配置的数量成为独立选择的纯粹产物。 该算法可以正确处理此问题，因为即使在`need = 0`，这会为每行生成一个有效的分配。 

最后，大小行的交替要求强调两个对角线系统之间的平衡。 如果一行将其所有需求推入一个系统，则即使总容量看起来足够，未来的行也可能变得不可行。 间隔检查$[lo, hi]$通过在每个步骤本地强制执行可行性而不是依赖于聚合计数来防止这种情况发生。
