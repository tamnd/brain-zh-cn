 ## 解决方案
 ## 问题理解

 我们有一个逐步构建数组的过程。 一开始数组是空的，然后按照值递增的顺序逐一插入从 1 到 n 的数字。 每个数字 i 都插入到当前数组中的指定位置 pi 处，并且该位置处或之后的所有内容都会右移，因此该结构始终是有效的序列。 

每次插入后，我们需要计算当前数组的最长递增子序列（LIS）的长度。 

关键的困难在于数组不仅在增长，而且还通过中间的插入来动态排列。 因此，LIS 不是基于静态数组前缀，而是基于通过位置插入操作演变的序列。 

约束允许 n 最大为 200000，因此每次插入后从头开始重新计算 LIS 的任何方法都太慢。 每步的单个 O(n^2) LIS 计算已经是每步的二次方，导致总工作量大约为 O(n^3)，这是完全不可行的。 即使所有步骤的总和为 O(n^2) 也太慢，因为 2e5 的平方大约为 4e10 次操作。 

因此，我们应该期待一个 O(n log n) 或 O(n log^2 n) 左右的解决方案，可能使用动态维护订单统计数据或类似 LIS 结构的数据结构。 

一个微妙的问题是，所有插入后的最终数组是 1 到 n 的排列，但中间状态不是该完整集合的随机排列； 它们是不断增长的集合的前缀排列。 任何依赖静态排列 LIS 技巧的解决方案都必须仔细处理不断演变的结构。 

打破天真的直觉的一种极端情况是插入严重向前倾斜。 例如，如果我们在位置 1 处插入每个下一个元素，则数组将变为 [n, n-1, ..., 1]，其中每一步都有 LIS 1。 “价值在增加，因此 LIS 应该增长”的天真的直觉在这里完全失败了，因为位置动态占主导地位。 

另一个边缘情况是交替插入，例如每次都插入到末尾，产生一个完美递增的数组 [1,2,3,...]，其中 LIS 等于当前大小。 任何忽视位置效应的方法都会错过这种单调增长。 

## 方法

 每次插入后，直接强力方法都会重新计算 LIS。 第 k 次插入后，我们有一个大小为 k 的数组，并且运行标准 O(k log k) 耐心排序 LIS 算法。 对所有 k 求和得出的总成本约为 n^2 log n，因为我们重复处理越来越大的数组。 即使没有对数因子，二次增长也占主导地位，并且对于 n 达到 200000 时变得太慢。 

关键的观察是，插入过程相当于构建 1 到 n 的排列，并且每个数字在插入时都是固定的。 我们不想重复重新计算 LIS，而是希望增量地维护 LIS。 困难在于，在中间插入一个元素会改变许多元素的相对位置，这使得直接 LIS 维护变得非常重要。 

处理这个问题的标准方法是反向重新解释该过程，或者将其建模为头寸的动态结构。 一个有用的观点是考虑为每个值 i 维护其在数组中的最终位置。 由于 i 是在所有值 1 到 i-1 都已存在时插入的，因此我们可以使用维护空槽的线段树来模拟构建最终排列。 每次插入都会将值 i 放入第 pi 个空位置。 

一旦我们根据位置重建最终的排列，就可以使用经典思想来计算该排列的 LIS：可以使用值上的 Fenwick 树或线段树来计算排列的 LIS，其中我们从左到右处理位置并维护以每个值结尾的最佳递增子序列。

然而，我们在每次插入之后都需要答案，而不仅仅是在最后。 这表明动态维护结构：放置每个 i 后，我们更新其位置并更新 LIS 贡献。 一个关键的见解是，我们可以按值顺序维护 dp[i]（以 i 结尾的 LIS），而位置则通过支持插入顺序统计映射的线段树进行管理。 

最终的解决方案简化为维护一个动态排列构建器，加上一个 LIS DP 值，其中 BIT 值按位置键控，并在每个新值插入其最终位置时增量更新。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每次插入后重新计算 LIS | O(n^2 log n) | O(n^2 log n) | O(n) | 太慢了 |
 | 线段树位置构建+BIT LIS维护| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 我们在位置上维护一个段树，存储每个段中剩余的空闲槽数。 最初所有位置都是空的，当我们插入值 1 到 n 时，我们将每个值放置到剩余空槽中的正确位置。 这使我们可以确定每个值的最终索引，而无需显式移动数组。 
2. 对于每个值 i，我们通过遍历线段树来定位其实际位置 pos[i]，始终根据剩余的空闲槽数来决定插入是进入左子树还是右子树。 此步骤确保我们有效地模拟换档过程。 
3. 一旦 pos[i] 已知，我们将 (pos[i], i) 视为排列中的一个点，其中 pos 是坐标，i 是值。 现在，当我们按 i 的递增顺序显示这些点时，我们希望保留这些点的 LIS。 
4. 我们在仓位上维护一棵 Fenwick 树，对于任何仓位，存储以该仓位结束的最大 LIS 长度。 在处理值i时，我们严格查询pos[i]之前的所有位置，以找到可以扩展的最佳LIS。 
5. 我们将 dp[i] 设置为 1 加上最佳查询结果，然后用 dp[i] 更新 pos[i] 处的 Fenwick 树。 这确保了未来的元素可以通过该位置扩展子序列。 
6. 每次插入后，答案是 Fenwick 树中存储的最大值，因为它代表迄今为止插入的所有元素中最好的 LIS。 

关键思想是我们将动态移位数组逐步转换为静态排列，然后按位置顺序应用标准 LIS DP。 

### 为什么它有效

 线段树保证 pos[i] 恰好是完全构造的数组中值 i 的最终索引，即使早期的插入移动了位置。 然后，芬威克树 DP 在 (pos[i], i) 定义的排列上计算 LIS。 由于我们按递增顺序处理值，因此每个有效的递增子序列都对应于位置递增的递增值序列，并且 DP 递归捕获所有此类扩展而不会丢失任何配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def update(self, i, v):
        while i <= self.n:
            if v > self.bit[i]:
                self.bit[i] = v
            i += i & -i

    def query(self, i):
        res = 0
        while i > 0:
            if self.bit[i] > res:
                res = self.bit[i]
            i -= i & -i
        return res

class SegTree:
    def __init__(self, n):
        self.n = n
        self.t = [0] * (4 * n)
        self.build(1, 1, n)

    def build(self, v, l, r):
        if l == r:
            self.t[v] = 1
            return
        m = (l + r) // 2
        self.build(v * 2, l, m)
        self.build(v * 2 + 1, m + 1, r)
        self.t[v] = self.t[v * 2] + self.t[v * 2 + 1]

    def kth(self, v, l, r, k):
        if l == r:
            return l
        m = (l + r) // 2
        if self.t[v * 2] >= k:
            return self.kth(v * 2, l, m, k)
        else:
            return self.kth(v * 2 + 1, m + 1, r, k - self.t[v * 2])

    def remove(self, v, l, r, idx):
        if l == r:
            self.t[v] = 0
            return
        m = (l + r) // 2
        if idx <= m:
            self.remove(v * 2, l, m, idx)
        else:
            self.remove(v * 2 + 1, m + 1, r, idx)
        self.t[v] = self.t[v * 2] + self.t[v * 2 + 1]

n = int(input())
p = list(map(int, input().split()))

seg = SegTree(n)
fen = Fenwick(n)

pos = [0] * (n + 1)
ans = []

for i in range(1, n + 1):
    idx = seg.kth(1, 1, n, p[i - 1])
    seg.remove(1, 1, n, idx)
    pos[i] = idx

    best = fen.query(idx - 1)
    dp = best + 1
    fen.update(idx, dp)

    ans.append(str(fen.query(n)))

print("\n".join(ans))
```线段树通过维护一组可用位置来处理移位插入过程。 每个第 k 个查询都会找到当前值所在的实际位置。 

Fenwick 树维护位置上的 LIS，其中更新只是单调改进，因此我们永远不需要减少值。 

一个常见的陷阱是忘记位置是 1 索引的，并且必须在剩余槽位上进行第 k 个选择，而不是在原始索引上进行。

 ## 边缘情况

 当所有元素都插入到位置 1 时，每个新元素都会按最终顺序放置在先前元素之后，即使每个操作概念上都插入到剩余空间的前面。 线段树确保正确的位置跟踪，而 Fenwick 树只是在位置的递增序列上累积 LIS，从而产生线性 LIS 增长。 

当所有元素都插入到它们自己递增的位置时，数组始终保持排序状态。 第 k 个选择机制将每个值分配给下一个可用位置，因此 pos[i] 等于 i。 然后，芬威克树会看到严格递增的位置序列，并且每次更新都会将 LIS 扩展 1，与直观结果相匹配。 

当插入在前后交替时，线段树会产生不平凡的排列，但 LIS DP 仍然正确，因为它仅取决于位置的相对顺序，而不取决于插入历史。 每个存储值都代表在给定位置结束的最佳子序列的 DP 不变量始终保持有效。
