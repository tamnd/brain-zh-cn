 ## 解决方案
 ## 问题理解

 我们得到一系列按坐标递增顺序放置在直线上的点。 每个点要么是加油站，要么是休息区。 我们还给出了最大允许距离`d`。 

我们需要计算有序的三元组点`(i, j, k)`这样`i < j < k`按照给定的顺序，最外面的两个点是加油站，中间的点是休息区，两个加油站之间的距离不超过`d`。 

由于坐标在输入中严格递增，因此索引顺序已与行上从左到右的顺序匹配。 所以“i < j < k”相当于“i在j的左边在k的左边”。 

因此，几何条件很简单：选择两个加油站作为区间的端点，区间的长度最多为`d`，并计算有多少个休息区严格位于它们之间。 

约束条件达到`5 × 10^5`点，这会立即排除三元组甚至所有点对上的任何二次枚举。 在最坏的情况下，当一半的点是加油站时，对所有加油站对进行简单的 O(n²) 扫描已经太慢了。 

如果试图修复一对加油站并通过扫描它们来计算中间点，则会出现一个更微妙的问题。 即使每次扫描都是线性的，在重叠范围内重复扫描也会导致密集情况下的立方行为。 

通常打破朴素推理的边缘情况包括所有点都是加油站、所有点都是休息区或加油站紧密聚集以致几乎每一对都满足距离约束的情况。 特别是，如果所有点都是加油站，则无论距离如何，答案都必须为零。 相反，如果有效气体对之间有许多休息区域，则每个休息区域都会独立贡献，如果结构不仔细组织，很容易被重复计算。 

## 方法

 蛮力策略很简单：迭代所有三元组`(i, j, k)`，检查类型和坐标约束，并统计有效的数量。 这是正确的，因为它直接遵循定义，但在最坏的情况下需要检查 O(n³) 三元组。 即使限制在加油站，在密集配置中也会将其降低到 O(g²r)，这仍然远远超出了`n = 5 × 10^5`。 

关键的观察是，一旦我们固定了端点，中间点就是独立的。 对于任何固定的加油站对`(i, k)`和`x_k - x_i ≤ d`，它们之间的每个休息区域都为该对贡献了一个有效的三元组。 因此，问题就变成了计算每个有效气体对在其区间内有多少个休息点。 

这建议按类型分离结构并使用前缀和。 一旦点按坐标排序，我们就可以维护休息区域的运行计数，并将“两个索引之间有多少休息点”转换为前缀值的差异。 剩下的挑战是仅对满足距离约束的加油站对进行有效迭代。 这是通过加油站上方的两指针窗口来处理的。 

我们扫过加油站的右侧端点。 对于每个右端点，我们保持最左边的加油站仍在距离内`d`。 此窗口中的所有加油站与当前右端点形成有效对。 我们不是单独枚举它们，而是使用前缀值的运行总和来聚合它们的贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解三倍 | O(n3) | O(1) | O(1) | 太慢了 |
 | 气体对+前缀+两个指针| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们对数组进行预处理，以便我们可以快速查询该行的任何前缀中存在多少个休息区域。 

1. 构建数组`pref_rest`， 在哪里`pref_rest[i]`是点之间休息区的数量`1`通过`i`。 这允许对任何分段中的休息点进行恒定时间计数。 
2.将所有加油站的索引提取到一个列表中`gas`。 我们只会针对主要逻辑迭代这些点。 
3. 使用两指针窗口`gas`列表。 让右指针`r`从左向右移动经过加油站。 
4. 保持左指针`l`这样距离约束适用于窗口中的所有加油站，这意味着`x[gas[r]] - x[gas[l]] ≤ d`。 当违反此规定时，我们将采取行动`l`向前。 这确保了每个加油站`[l, r]`是有效的左端点`gas[r]`。 
5. 处理固定右端点时`r`，我们想要对所有左端点的贡献求和`i`在窗口中。 对于每对`(i, r)`，有效中点的个数为`pref_rest[r_idx - 1] - pref_rest[i_idx]`， 在哪里`i_idx`和`r_idx`是它们在数组中的原始位置。 
6. 将总和分摊给所有的人`i`在窗口中：

 - 术语`pref_rest[r_idx - 1]`是固定不变的`r`，所以它贡献了`(window_size) * pref_rest[r_idx - 1]`。 
- 期限`-pref_rest[i_idx]`需要维持总和`pref_rest[i_idx]`覆盖当前窗口中的所有加油站。 
7. 保持流动金额`sum_pref`的`pref_rest[i_idx]`对于当前窗口中的加油站，随着窗口滑动而更新。 
8. 对于每个`r`， 添加：`window_size * pref_rest[r_idx - 1] - sum_pref`到答案。 

### 为什么它有效

 正确性取决于两个耦合的不变量。 首先，滑动窗口始终准确地表示在距离约束下可以与当前右端点合法配对的加油站集合。 其次，对于每个这样的对，有效中间点的数量仅取决于前缀计数并在左端点上线性分解。 

因为每个有效的三元组都由正确加油站的选择唯一地表示`k`，离开加油站`i`，以及它们之间的休息站，并且因为每对的贡献仅计算一次`k`处理后，不会发生多计或少计的情况。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, d = map(int, input().split())
x = []
t = []

for _ in range(n):
    xi, ti = map(int, input().split())
    x.append(xi)
    t.append(ti)

pref_rest = [0] * (n + 1)
for i in range(n):
    pref_rest[i + 1] = pref_rest[i] + (1 if t[i] == 0 else 0)

gas = [i for i in range(n) if t[i] == 1]

ans = 0
l = 0
sum_pref = 0

for r in range(len(gas)):
    ri = gas[r]

    while l < r and x[ri] - x[gas[l]] > d:
        sum_pref -= pref_rest[gas[l] + 1]
        l += 1

    # add current right endpoint contribution
    window_size = r - l
    if window_size > 0:
        ans += window_size * pref_rest[ri] - sum_pref

    sum_pref += pref_rest[ri + 1]

print(ans)
```代码的核心结构完全遵循加油站的滑动窗口。 前缀数组是一次性构建的。 两指针循环确保每个加油站最多进入和离开窗口一次。 

一个微妙的实现细节是前缀值被视为`pref_rest[i+1]`气体指数`i`， 因为`pref_rest`是在原始数组索引移一的基础上定义的。 此处混合基于 0 和基于 1 的索引是最常见的差一错误来源。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 前缀计算中每个点处理一次，每个加油站最多进出滑动窗口一次 |
 | 空间| O(n) | 前缀数组和gas索引列表|

 线性复杂度对于处理高达`5 × 10^5`时限内的积分。 该算法避免了任何成对枚举，并将问题简化为对加油站进行单次扫描。

    x = []
    t = []
    for _ in range(n):
        xi, ti = map(int, input().split())
        x.append(xi)
        t.append(ti)

    pref_rest = [0] * (n + 1)
    for i in range(n):
        pref_rest[i + 1] = pref_rest[i] + (1 if t[i] == 0 else 0)

    gas = [i for i in range(n) if t[i] == 1]

    ans = 0
    l = 0
    sum_pref = 0

        while l < r and x[ri] - x[gas[l]] > d:

            l += 1

        if r - l > 0:
            ans += (r - l) * pref_rest[ri] - sum_pref

        sum_pref += pref_rest[ri + 1]

    return str(ans)

 ## 边缘情况

 当所有点都是加油站时，前缀结构仍然可以正确构建，但汽油列表成为完整索引集。 滑动窗口可能包含许多对，但每个贡献的计算结果为零，因为`pref_rest`在气体位置始终为零。 该算法自然累加零，无需特殊处理。 

当所有点都是休息区时，气体列表为空。 加油站上的循环永远不会运行，因此不会添加任何贡献，答案仍然为零。 这避免了任何防范空结构的需要。 

当加油站在坐标空间中非常接近时，窗口会扩展以包含许多左端点。 该算法仍然表现正确，因为每个左端点通过维护的前缀和独立贡献，并且由于对右端点的严格单次传递，没有一对被重复计算。
