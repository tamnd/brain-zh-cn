 ## 解决方案
 ## 问题理解

 我们得到了一个完整的加权图$n$玩家。 玩家之间的权重$i$和玩家$j$是一个对称值$P_{i,j}$，这代表这两名玩家进行比赛时的人气增益。 

一场比赛总会淘汰一名球员。 排序规则是固定的：如果$i < j$, 玩家$i$总是赢。 一场比赛结束后，球员$i$击败玩家$j$, 玩家$i$吸收玩家$j$的受欢迎度概况，意味着三分之一的玩家$x$，值$P_{i,x}$变成$\max(P_{i,x}, P_{j,x})$。 对称地，$P_{x,i}$以同样的方式更新，因此有效播放器$i$成为矩阵中两行的并集。 

我们必须准确选择$n-1$比赛，形成淘汰赛流程，将所有选手淘汰为最终获胜者。 比赛必须按顺序进行，每场比赛结束后，失败者都会消失，获胜者行会在下一场比赛之前更新。 

之间的比赛比分$i$和$j$始终是当前值$P_{i,j}$在匹配发生时，在所有先前的合并都更新了矩阵之后。 目标是选择配对结构和比赛顺序，以最大化这些比赛得分的总和。 

约束条件$n \le 1000$意味着任何$O(n^2)$或者$O(n^2 \log n)$策略是合理的，但任何更接近的策略$O(n^3)$除非每次迭代都经过大量优化或非常简单，否则是危险的。 我们还需要输出实际的消除顺序，而不仅仅是值。 

一个微妙的点是矩阵条目随着时间的推移而演变，每次合并后重新计算最大更新的简单模拟很容易变得$O(n^3)$或者更糟。 另一个陷阱是假设匹配的结构是任意的，而实际上“较小的索引总是获胜”的约束强制采用有向结构。 

更新级联时出现极端情况：合并后$i$和$j$，获胜者可以突然增加对未来对手的权重，改变​​下一场比赛的最优选择。 忽视未来增长的贪婪选择可能会失败。 

## 方法

 一个直接的暴力想法是模拟锦标赛：在每一步，尝试所有剩余的对，模拟合并，计算结果状态，然后递归。 这在概念上是正确的，因为它探索了所有可能的锦标赛树和顺序，但分支因子大致为$O(n^2)$每个级别都有深度$n$。 即使使用记忆化，状态空间也是所有可能的子集加上所有可能的合并矩阵的集合，这是一个天文数字。 瓶颈不仅在于组合爆炸，还在于每次假设匹配后更新矩阵的成本，即$O(n)$每次更新，至少导致$O(n^3)$每条路径。 

关键的结构观察是获胜者规则确定了方向：每当两个活着的玩家之间发生比赛时，较小的索引总是生存。 这将这个过程转变为建立一个根深蒂固的结构，其中较高指数的参与者逐渐被较低指数的代表所吸收。 因此，每个玩家最终都会被同一个索引较小的祖先所吸收。 

这建议颠倒该过程。 我们可以考虑通过按索引升序逐步合并组件来构建最终的幸存者，而不是模拟消除，始终将较大的索引附加到一些较小的索引中。 合并操作是确定性的，因此剩下的就是决定最大化边缘增益的附件序列。 

现在以不同的方式解释该过程：在任何时刻，每个活着的玩家都代表一组原始玩家，并且其行是该组中的元素最大值。 如果我们决定那个球员$j$被吸收到$i$，那么我们得到$P_{i,j}$在那一刻，以及未来的价值$i$变得丰富$j$的行。 

这成为最大生成树状结构，但具有动态权重效应：合并通过最大传播改善未来的边权重。 关键的观察是，对于任何两个组件，最佳的立即合并取决于它们的代表之间的当前最大边缘，并且一旦合并，所得的代表只会增加权重，而不会减少权重。 这种单调性使我们能够使用优先级结构贪婪地维持组件之间的最佳可能连接。 

最终的解决方案可以被视为在不同组件之间的所有边中重复选择最佳可能的下一个匹配，合并它们，并通过最大传播更新受影响的边。 这就像动态权重下的最大生成树构造一样，其中类似 Prim 的贪心算法起作用，因为合并操作只会增加未来的边权重，从而保留本地决策的有效性。

 ## 算法演练

 我们维护一组不相交的活动组件，每个组件代表一个合并的玩家。 每个组件都有一个代表性索引，始终是其中最小的索引，以遵守较小索引获胜合并的规则。 

我们还维护组件之间当前最佳权重的矩阵，当组件统一时，该矩阵通过最大合并而演变。 

### 步骤

 1.将每个播放器初始化为自己的组件，并将每个组件的当前代表设置为播放器本身。 当前矩阵最初是$P$。 
2. 对于每对$(i, j)$，保持其组件之间当前可实现的最佳边缘权重。 最初这只是$P_{i,j}$。 
3. 重复选择一对不同的组件$(A, B)$最大化当前值$P_{rep[A], rep[B]}$。 这是最好的即时匹配。 
4. 进行一场比赛$rep[A]$和$rep[B]$。 由于较小的指数总是获胜，因此具有较小指数的代表会吸收另一个。 
5. 将匹配项添加到输出中，并将其得分添加到总分中。 
6. 将失败的部分合并到获胜的部分。 对于所有其他组件$C$， 更新：$$P_{win, C} = \max(P_{win, C}, P_{lose, C}), \quad P_{C, win} = P_{win, C}$$这模拟了流行度的继承。 
7. 将丢失的组件标记为非活动状态并继续，直到只剩下一个组件。 

### 为什么它有效

 核心不变量是，对于任何一对活动组件，它们存储的边权重始终等于当前在这些组件内的任何原始玩家对在所有先前合并之后可获得的最大可能值。 因为合并只取元素最大值，所以未来的操作不能减少任何边权重，只能增加它。 

这种单调性保证了选择最大当前边缘是安全的：未来对边缘的任何改进只能增加已经形成的组件内部的权重，而永远不会创建以前不可用的更好的跨组件选择。 因此，贪婪的选择永远不会阻止最佳的未来合并结构，并且该过程的行为就像非递减边缘更新下的最大生成树。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    P = [list(map(int, input().split())) for _ in range(n)]

    parent = list(range(n))
    alive = [True] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    # current representative is always smallest index in component
    def merge(a, b):
        ra, rb = find(a), find(b)
        if ra == rb:
            return ra
        if ra > rb:
            ra, rb = rb, ra

        parent[rb] = ra
        alive[rb] = False

        for k in range(n):
            if alive[k] and k != ra:
                P[ra][k] = max(P[ra][k], P[rb][k])
                P[k][ra] = P[ra][k]
        return ra

    active = set(range(n))
    total = 0
    edges = []

    import heapq
    heap = []

    for i in range(n):
        for j in range(i + 1, n):
            heapq.heappush(heap, (-P[i][j], i, j))

    while len(active) > 1:
        w, i, j = heapq.heappop(heap)
        w = -w
        i = find(i)
        j = find(j)
        if i == j or not alive[i] or not alive[j]:
            continue

        if i > j:
            i, j = j, i

        total += P[i][j]
        edges.append((i + 1, j + 1))

        new_rep = merge(i, j)

        # push updated edges from new_rep
        for k in list(active):
            rk = find(k)
            if rk != new_rep:
                heapq.heappush(heap, (-P[new_rep][rk], new_rep, rk))

        # rebuild active set lazily
        active = {find(x) for x in active if alive[find(x)]}

    print(total)
    for u, v in edges:
        print(u, v)

if __name__ == "__main__":
    solve()
```该实现维护一堆候选边，始终提取当前最佳的可用匹配。 由于合并会改变权重，因此当过时的堆条目的端点不再代表有效的活动组件时，它们会被延迟地跳过。 

合并操作是正确性所在：选择获胜者后，我们将最大值从失败者传播到所有剩余活动节点的获胜者，完全模拟“继承流行度”规则。 

一个常见的陷阱是忘记边权重随时间变化，因此仅静态优先级队列是不够的，除非我们在提取时验证代表。 

## 工作示例

 考虑一个由三名玩家组成的小实例：

 输入矩阵：$$P =
\begin{bmatrix}
0 & 5 & 1 \\
5 & 0 & 4 \\
1 & 4 & 0
\end{bmatrix}$$我们从组件开始$\{1\}, \{2\}, \{3\}$。 

| 步骤| 选择边缘| 组件| 合并结果 | 分数 |
 | --- | --- | --- | --- | --- |
 | 1 | (1,2) | {1,2}, {3} | 1 吸收 2 | 5 |
 | 2 | (1,3) | {1,2,3} | 1 吸收 3 | 1 |

 总计为$6$。 合并 1 和 2 后，第 1 行变为$[0,5,1]$。 合并 3 不会将已经很高的边缘更改为 2，因为 3 对除 2 之外的所有维度的影响都很弱，2 已经由 2 主导。 

该跟踪表明，早期的高权重边缘被安全地采用，因为后来的合并只会增加或保留相关比较。 

现在考虑延迟福利很重要的情况：$$P =
\begin{bmatrix}
0 & 2 & 100 \\
2 & 0 & 3 \\
100 & 3 & 0
\end{bmatrix}$$| 步骤| 选择边缘| 组件| 合并结果 | 分数 |
 | --- | --- | --- | --- | --- |
 | 1 | (1,3) | {1,3}, {2} | 1 吸收 3 | 100 | 100
 | 2 | (1,2) | {1,2,3} | 1 吸收 2 | 2 |

 这里，首先合并 1 和 3 会立即解锁最强的边缘，后续合并不会减少该增益。 

这些例子证实了贪婪提取与最大化即时高价值合并同时安全地保留未来的可能性是一致的。

 ## 边缘情况

 单人玩家的情况很简单，因为没有匹配发生。 该算法立即输出总数为零且没有边缘，因为活动集从一开始就有大小一。 

完全均匀的矩阵（其中所有非对角值都相等）测试基于堆的平局打破是否产生有效序列。 由于所有边都是相同的，因此任何合并顺序都是最佳的，并且算法可以选择任意对，同时由于对称性和单调合并而仍然保持正确性。 

在主导对配置中，一条边明显大于所有其他边，这证实了该算法首先优先考虑合并。 合并主导对后，传播会增加权重，但不能创造更好的初始错过机会，因为最大的边缘已经被贪婪地占据。 

小链结构测试中间合并是否不会阻塞未来的高价值边缘。 由于每次合并都会增加或保留权重，因此该算法可以安全地延迟或加速合并，而不会丢失最佳结构。
