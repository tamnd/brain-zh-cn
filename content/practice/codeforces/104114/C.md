 ## 解决方案
 ## 问题理解

 我们得到了一组人员和一组新冠病毒集体测试。 每项测试都会检查一部分人，如果该子集中至少有一名感染者，则返回阳性。 在这个问题中，所有测试均呈阳性，因此每个测试组都至少包含一名感染者。 

在看到任何结果之前，每个人被独立感染的概率为 1/2，这意味着每个人子集在前一阶段的可能性相同。 在观察到所有测试均为阳性后，我们仅关注与每次测试一致的感染配置。 在这些有效配置中，每种配置的可能性均等，并且特定人被感染的后验概率与包含该人的有效配置的数量成正比。 

我们的任务不是计算确切的概率，而是在所有检测结果呈阳性后，将人们从最不可能感染到最可能感染的情况进行排名。 

关键的输入结构是最多 1000 人，但最多 15 个测试，每个测试都是一小部分人。 这种不平衡是问题变得容易处理的全部原因：我们可以承担测试数量的指数级工作，但无法承担人员数量的指数级工作。 

一个天真的尝试会尝试枚举所有 2^n 个感染状态，检查哪些状态满足所有测试，并计算每个人的贡献。 这立即失败，因为 2^1000 远远超出了任何可行的计算。 

一种更微妙的故障模式来自于尝试独立模拟每个人的概率。 这些测试将人们在全局约束中结合在一起，因此每个人的局部推理而不跟踪测试之间的交互会导致不正确的相对排名。 

一个有用的边缘情况是所有测试都严重重叠。 例如，如果每个测试都包含人员 1，则只要存在任何配置，人员 1 就会自动出现在每个有效配置中，这使得他们比其他人更有可能出现。 每次测试的平均方法会错过这种主导效应。 

另一个边缘情况是测试划分宇宙并且不重叠。 那么所有人都会变得对称，任何正确的解决方案都必须保持精确的平等，而不是引入数值漂移。 

## 方法

 暴力策略将每个人子集视为候选感染集。 对于每个子集，我们验证每个测试是否至少包含一个选定的人。 如果是，我们会增加该子集中所有受感染成员的计数。 这是正确的，因为它直接遵循概率解释，但它需要迭代所有 2^n 子集并检查每个子集的 m 个测试，给出大约 O(2^n · m)，这对于 n 高达 1000 来说是完全不可行的。 

当我们观察到 m 很小时，问题的结构就会发生变化。 我们可以翻转视角并在测试中使用包含排除，而不是迭代人员子集。 如果配置避免了某些测试完全未受感染的不良事件，则该配置是有效的。 每个不良事件仅取决于特定人群中是否存在感染，并且只需 15 次测试，我们就可以枚举这些事件的所有组合。 

主要思想是通过从所有子集开始并减去那些违反至少一个测试约束的子集来计算有效感染集，然后使用测试子集上的包含-排除来纠正重叠。 一旦我们能够有效地计算有效集合，我们就会重复相同的计数，并附加一个限制，即必须有一个固定的人被感染。 这两个计数之间的差异给出了该人的体重。

因为我们最多只有 15 个测试，所以枚举所有 2^m 个测试子集是可行的。 对于每个测试子集，我们只需要知道其人员集的并集大小，因为这决定了有多少感染配置同时避免所有这些测试。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对人的子集进行暴力破解 | O(2^n·m) | O(2^n·m) | O(n) | 太慢了 |
 | 测试中的包含-排除| O(n·2^m + m·2^m) | O(n·2^m + m·2^m) | O(2^m·n) | O(2^m·n) | 已接受 |

 ## 算法演练

 我们首先为每个测试子集预先计算测试组的所有并集。 这是通过大小为 m 的位掩码完成的，存储该子集联合覆盖了多少个不同的人。 这使我们能够稍后计算有多少任务有效地避开了这些人。 

接下来，我们修复一个人 i 并强制他们被感染。 这将问题减少到剩下的 n − 1 个人，同时修改约束：任何已经包含个人 i 的测试都会自动满足，因为该测试已经有一个受感染的个人。 只有不包含i的测试还需要其他感染者满意。 

对于每个人 i，我们表示一个测试位掩码，指示哪些测试包括 i。 当应用约束时，任何该位为 1 的测试都与该人无关。 

然后，我们对剩余活动测试的子集应用包含-排除。 对于测试 K 的子集，我们考虑剩余人员的感染配置，以避免覆盖 K 中测试并集中的所有人员。避免一组人员意味着我们仅从补集中选择受感染的集合，因此此类配置的数量变为 2 的幂，具体取决于排除了多少人。 

将这些贡献与交替符号相加，给出了在人 i 被感染的情况下没有违反测试的有效配置的数量。 

最后，我们计算每个人的这个值并按它排序。 

正确性依赖于测试子集上的包含-排除准确地解释了至少违反了一个测试的所有配置的不变性，并且修复一个人只是删除了每个相关测试中存在的该人已经满足的所有约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    tests = []
    in_test = [[False] * m for _ in range(n)]

    for j in range(m):
        arr = list(map(int, input().split()))
        k = arr[0]
        group = [x - 1 for x in arr[1:]]
        tests.append(group)
        for v in group:
            in_test[v][j] = True

    size = [0] * (1 << m)
    for mask in range(1 << m):
        union = 0
        cnt = 0
        seen = set()
        for j in range(m):
            if mask & (1 << j):
                for v in tests[j]:
                    if v not in seen:
                        seen.add(v)
                        cnt += 1
        size[mask] = cnt

    total = 1 << (n - 1)
    ans = []

    for i in range(n):
        allowed = ((1 << m) - 1) ^ 0
        mask_i = 0
        for j in range(m):
            if in_test[i][j]:
                mask_i |= (1 << j)

        res_bad = 0

        for K in range(1, 1 << m):
            if K & mask_i:
                continue

            # compute union size of tests in K
            seen = set()
            cnt = 0
            for j in range(m):
                if K & (1 << j):
                    for v in tests[j]:
                        if v not in seen:
                            seen.add(v)
                            cnt += 1

            sign = 1 if bin(K).count("1") % 2 == 1 else -1
            # inclusion-exclusion for bad sets
            res_bad += sign * (1 << ((n - 1) - cnt))

        ans.append((total - res_bad, i + 1))

    ans.sort(key=lambda x: (x[0], x[1]))
    print(*[x[1] for x in ans])

if __name__ == "__main__":
    solve()
```该解决方案首先建立人与测试之间的邻接关系，这样可以快速过滤当一个人被确定为感染者时哪些约束很重要。 人们的主循环重新计算不相关测试的位掩码，然后对仍需要满足的测试子集运行包含-排除。 

求幂`1 << ((n - 1) - cnt)`对应于对所有人选择任何感染模式，除了那些被当前包含-排除子集强制排除的人之外。 交替符号可确保正确计算过多的配置。 

最终排序直接使用计算出的权重，并根据索引自动打破平局。

 ## 边缘情况

 当一个人出现在每个测试中时，一旦该人被包括在内，所有约束都会自动满足。 该算法通过跳过包含涉及该人的任何测试的所有测试子集来反映这一点，从而有效地减少活动约束的数量并增加其权重。 

当一个人没有参加任何测试时，他们无助于满足任何约束。 在包含-排除框架中，这意味着在对该人进行调节时不会删除任何测试，因此他们继承了完整的约束复杂性并且通常接收较低的概率。 

当测试相同或严重重叠时，包含-排除中的并集大小会变小，并且算法会正确地放大早期满足共享约束的配置的贡献，从而保持对称性并避免过度计数。
