 ## 解决方案
 ## 问题理解

 我们有 2n 个学生的集合，每个学生都有一个数字技能值。 最初，它们被分组为固定对，特别是连续索引，因此学生 1 与 2 配对，学生 3 与 4 配对，依此类推。 任务是将所有学生完全重新配对成n对新的配对，同时遵守一个限制：不允许原来的配对在新的排列中再次出现。 

每个新配对所贡献的成本等于两个学生技能值的绝对差。 目标是选择有效的重新配对，最大限度地降低所有配对的总成本。 

结构很重要：每个学生必须只使用一次，并且禁止对恰好是原始的 n 个不相交边。 

约束 n 最多 100000 意味着 2n 最多 200000 个元素。 任何解必须接近线性或 n log n。 对所有学生采用三次甚至二次配对策略是不可能的，因为枚举所有匹配或检查任意对之间的兼容性将需要 (2n)^2 或更多的操作。 

当我们尝试简单地对所有值进行排序并对邻居进行配对时，就会出现天真的贪婪配对的微妙失败案例。 这是不正确的，因为它可能会意外地重新创建禁止的对。 

例如，假设我们有 n = 2 和值：```
1 2 3 4
```原始对是 (1,2) 和 (3,4)。 排序保持相同的顺序。 将相邻元素配对给出 (1,2) 和 (3,4)，这是被禁止的，即使它在无约束匹配下是最佳的。 正确的解决方案必须稍微扰乱匹配结构以避免这些固定边缘。 

另一个常见的陷阱是在每个原始对内进行本地交换。 这每对只产生两个选择，并且忽略了跨对相互作用，这限制性太大，并且可能会错过最佳的全局重排。 

## 方法

 暴力方法会考虑 2n 个节点上所有可能的完美匹配，同时排除 n 个禁止边。 完美匹配的数量是指数级的，大约是（2n）！ / (2^n n!)，即使修剪禁止边也不足以将其减少到可行的程度。 即使子集上的 DP 也需要 O(2^(2n)) 状态，这对于 2n 到 200000 来说是不可能的。 

关键的观察是禁止结构非常规则：它是连续索引的完美匹配。 这表明将成对的原子单元视为原子单元，然后决定这些单元如何相互作用。 

如果我们按技能对所有学生进行排序，则无约束的最佳匹配会将相邻元素配对。 唯一的问题是一些相邻元素与禁止对完全对应。 所以问题就变成了：我们如何“修复”一个已排序的完美匹配，同时避免连接两个已知位置的 n 个特定边？ 

看待这一问题的一个有用方法是，每个原始对都可以视为一个段，每个段贡献两个候选。 在排序后的最佳解决方案中，我们希望按顺序匹配元素，但每当出现禁止边时，我们必须通过在相邻对之间交换伙伴来“跳过”它。 这自然会导致排序顺序上的动态编程，其中转换仅取决于连续元素的局部结构。 

由此产生的解决方案简化为排序，然后贪婪地构建对，同时考虑到如果两个连续元素形成禁止对，我们必须以避免该边缘同时保持成本最小的唯一方式跨边界进行配对。 这种局部修复结构确保我们永远不需要全局搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力匹配| O((2n)!) | O((2n)!) | O(n) | 太慢了 |
 | 排序+本地修复匹配| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取所有 2n 个值，同时记住它们的原始索引。 索引很重要，因为禁止对是由固定索引结构定义的，而不是由值定义的。 
2. 按技能值对学生进行排序，同时跟踪原始指数。 排序后，无约束的最佳配对将简单地匹配连续元素。 
3. 从左到右迭代排序列表，并尽可能尝试将 i 与 i + 1 配对。 这是最小化绝对差异的自然贪婪结构。 
4. 在提交对 (i, i + 1) 之前，检查它们的原始索引是否形成禁止对，这意味着它们来自同一个初始 (2j − 1, 2j) 块。 如果他们不这样做，我们就接受这对。 
5. 如果它们确实形成禁止配对，我们必须避免将它们配对。 相反，我们在本地转移配对：我们将 i 与 i + 2 配对，将 i + 1 与 i + 3 配对，从而有效地交换邻接结构。 这保留了排序顺序的最优性，同时消除了无效边缘。 
6. 继续该过程，在执行交换时适当跳过索引，确保每个元素仅使用一次。 

关键思想是冲突仅发生在源自同一原始对的连续排序元素之间。 解决这样的冲突只需要对四个元素进行本地重新配置。 

### 为什么它有效

排序后，任何没有约束的最优解都必须按相邻顺序对元素进行配对，因为成本函数在排序顺序中是凸的。 与此结构的唯一偏差来自禁止边缘。 仅当两个连续的排序元素源自同一初始对时，每个禁止边才会出现。 当发生这种情况时，任何最佳匹配都必须避免该边缘，而最便宜的替代方案是以保留排序邻接性的唯一方式重新连接这四个元素。 由于冲突是局部的，并且不会以需要全球协调的方式重叠，因此从左到右贪婪地解决冲突可以始终保持最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = list(map(int, input().split()))
    
    a = [(c[i], i // 2) for i in range(2 * n)]
    a.sort()
    
    used = [False] * (2 * n)
    ans = 0
    
    i = 0
    while i < 2 * n - 1:
        if used[i]:
            i += 1
            continue
        
        j = i + 1
        while j < 2 * n and used[j]:
            j += 1
        
        if j >= 2 * n:
            break
        
        if a[i][1] != a[j][1]:
            ans += abs(a[i][0] - a[j][0])
            used[i] = used[j] = True
            i += 1
        else:
            k = j + 1
            while k < 2 * n and used[k]:
                k += 1
            if k >= 2 * n:
                break
            ans += abs(a[i][0] - a[k][0]) + abs(a[j][0] - a[k+1][0] if k + 1 < 2 * n else 0)
            used[i] = used[k] = True
            used[j] = used[k+1] = True
            i += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先使用整数除以 2 为其原始配对标识符标记每个学生。按技能排序后，这允许对禁止配对进行恒定时间检查。 

贪婪扫描使用一个指针，该指针始终尝试将最早的未使用元素与下一个可用的未使用元素进行匹配。 这保持了排序后的最优结构。 当出现禁止对时，算法会在下一个可用元素上执行本​​地重新路由，确保不会重建原始对。 

关键的实现细节是跳过已经使用的元素。 如果没有这个，指针逻辑将错误地重用元素或形成无效的重叠。 这`used`数组确保正确性，但也保留线性行为。

 ## 边缘情况

 当每个连续的排序对都属于相同的原始对结构时，就会出现一种边缘情况。 在像这样的输入中`1 2 100 101`，排序会重复产生相邻的禁止对。 该算法检测每个禁止的邻接并执行本地交换，确保没有无效的配对存在。 结果仍然是最佳的，因为每次交换仅用相同的四个元素中最便宜的替代连接替换一个禁止边缘。 

另一个边缘情况是当值严重聚集时，会连续触发许多交换。 从左到右的扫描仍然有效，因为每次交换都会消耗固定的元素块，从而防止级联歧义。
