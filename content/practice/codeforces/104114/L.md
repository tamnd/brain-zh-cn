 ## 解决方案
 ## 问题理解

 游戏由一系列必须按顺序清除的领域组成。 玩家从领域 1 开始，等级为 1，初始生命值由我们自由选择。 每个领域都包含一小部分敌人，并且在每个领域中玩家选择这些敌人的非空子集进行战斗。 

领域内的战斗完全由所选子集决定。 当任何选定的敌人仍然活着时，所有当前活着的敌人都会造成等于其力量总和的伤害，然后玩家每回合只能杀死一个活着的敌人。 每次击杀都会使玩家的等级提高一级，最高可达固定的最高等级 m。 在一个领域中所有选定的敌人被击败后，玩家根据他们的最终等级进行治疗，然后进入下一个领域。 我们的目标是完成所有领域，同时最终达到 m 级，我们希望有最低的初始生命值来实现这一目标。 

关键的困难在于，选择在每个领域中战斗的敌人子集决定了伤害模式和我们获得的升级数量。 由于等级会影响后期的治疗，因此早期的决定会影响所有后期领域。 

这些约束已经表明我们不能以简单的方式模拟任意子集。 境界最多有100个，每个境界最多可以容纳2000个敌人，而敌人总数至少为m−1，因此达到m级需要总共杀死至少m−1个敌人。 m 的值最大可达 50,000，因此级别进展是系统的全局状态，而不是我们可以以指数方式针对每个领域独立重新计算的东西。 

一个天真的想法是尝试每个领域的所有敌人子集，甚至根据局部伤害效率贪婪地选择子集。 两者都失败了，因为伤害排序和等级增益之间的相互作用是全局的。 

当一个领域包含许多弱敌人和一些强敌人时，就会出现微妙的边缘情况。 尽早与强大的敌人战斗会显着增加即时伤害，但可能会减少每单位伤害的可用升级次数。 相反，只与弱小的敌人战斗可能会因为重复的全套攻击而被迫进行多次回合并增加总伤害。 

另一个边缘情况是，跳过某个领域中的敌人似乎是有益的，但实际上会阻碍尽早达到 m 级，这会改变稍后的治疗值，并使路径不可行，即使局部生命值似乎足够。 

## 方法

 直接的暴力方法将尝试为每个领域选择敌人的子集和杀戮顺序，然后模拟完整的游戏。 即使忽略排序，每个领域也最多有 2^{2000} 个子集，所以这是完全不可行的。 即使我们限制自己只考虑子集大小，跨领域的可能性数量也会以 n 为指数。 

第一个关键观察结果是，在选定的领域子集中，最佳游戏顺序由敌人的强度决定。 在任何时刻，所有活着的敌人都会造成全部综合伤害，因此让强大的敌人存活更长时间只会增加总累积伤害。 这意味着对于固定的子集，最佳策略是以非递增的强度顺序杀死敌人，始终删除当前最强的剩余敌人。 

一旦我们修复了这个顺序，每个子集都会在伤害和击杀数量方面产生确定性成本，这对应于等级增益。 

第二个观察结果是我们实际上不需要考虑任意子集。 对于每个领域，如果我们按强度对敌人进行排序，则任何最佳子集都对应于采用此排序顺序的前缀。 这是因为，如果我们跳过弱小的敌人而选择更强的敌人，我们只会在早期回合中增加伤害，而不会以有帮助的方式改变升级次数。

因此，每个领域都可以简化为选择我们包含多少个最弱的敌人，然后模拟以最佳杀戮顺序捕获 k 个最弱敌人的成本（这实际上是在所选集合中从最强到最弱的顺序进行杀戮）。 

现在问题变成了全局DP的等级问题：每杀死一个敌人就会增加一级，而我们必须达到m级。 所有领域的击杀总数固定为 m − 1，因此我们本质上是在跨领域分配这些升级，同时最大限度地减少所需的初始 HP。 

对于每个领域以及从中获得的每个可能的杀戮数量，如果我们最佳地消灭了 k 个敌人，我们就可以计算出该领域中产生的总伤害。 这会产生一个转换列表：从级别 x 到 x + k，具有伤害成本，加上取决于最终级别的治疗效果。 

然后，我们在各个级别上执行类似最短路径的 DP，其中状态是进入给定级别的领域之前所需的最低运行状况。 转换来自于在当前领域中选择 k 个敌人，增加伤害成本，然后根据最终等级在领域后应用治疗。 

这种结构允许我们将每个领域视为级别上的小型转换图，并且全局解决方案成为分层 DP 转换的序列。

 ## 算法演练

 我们一个接一个地处理领域，同时维护一个 DP 数组，其中 dp[l] 表示进入当前 l 级领域所需的最小生命值。 

对于每个领域，我们计算捕获 k 个敌人如何改变状态。 

1.将敌人按实力从高到低排序。 这确保了当我们模拟杀戮时，我们总是先消灭剩下的最强敌人，从而最大限度地减少累积伤害。 
2. 按此顺序构建强度的前缀和。 当多个敌人同时存活时，这些前缀总和可以快速计算总伤害贡献。 
3. 对于从 1 到 ki 的每个可能的 k，计算如果我们消灭 k 个敌人所造成的总伤害。 伤害模式的出现是因为当 k 个敌人还活着时，每一回合都会贡献所有剩余力量的总和，并且随着我们一个接一个地杀死敌人而减少。 
4. 将每个 k 解释为一个过渡：从 l 级开始，击杀 k 次将我们移动到 min(m, l + k) 级，成本是对这 k 个敌人的计算伤害。 
5. 对于每个领域，用大值初始化一个新的 DP 数组 ndp。 对于每个起始级别 l，尝试所有有效的 k，使得 l + k 不超过 m + 1，使用 dp[l] 加上伤害更新 ndp[l + k]，然后在完成级别 l + k 的领域后减去治疗效果。 
6. 将 dp 替换为 ndp 并继续下一个领域。 

答案是 dp[m]，表示处理完所有领域后达到 m 级所需的最低初始生命值。 

### 为什么它有效

 正确性取决于这样一个事实：在任何子集中，延迟清除更强的敌人只会增加总伤害。 因此，通过降低强度进行排序给出了最佳的内部顺序。 一旦这个顺序被固定，消灭 k 个敌人的成本就变得确定并且独立于任何其他领域。 然后，DP 仅跟踪累积的击杀次数，并且由于每次击杀完全对应于一次升级，因此我们永远不会丢失或重复状态。 治疗功能仅取决于最终级别，因此仅在完成每个领域后才应用它可以保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    h = list(map(int, input().split()))
    
    realms = []
    for _ in range(n):
        arr = list(map(int, input().split()))
        k = arr[0]
        mobs = arr[1:]
        mobs.sort(reverse=True)
        realms.append(mobs)

    INF = 10**30
    
    dp = [INF] * (m + 1)
    dp[1] = 0  # start at level 1 with 0 required damage taken so far

    for mobs in realms:
        k = len(mobs)

        # prefix sums of sorted strengths
        pref = [0] * (k + 1)
        for i in range(k):
            pref[i + 1] = pref[i] + mobs[i]

        ndp = [INF] * (m + 1)

        for lvl in range(1, m + 1):
            if dp[lvl] == INF:
                continue

            # try taking t enemies
            cur_sum = 0
            for t in range(1, k + 1):
                if lvl + t > m:
                    break

                # compute damage for taking first t strongest enemies
                # each remaining set contributes repeatedly; derive incremental cost
                cur_sum += pref[t]

                new_lvl = min(m, lvl + t)
                cost = dp[lvl] + cur_sum

                # apply healing based on final level
                heal = h[new_lvl - 1] if new_lvl >= 1 else 0
                cost -= heal

                if cost < ndp[new_lvl]:
                    ndp[new_lvl] = cost

        dp = ndp

    print(dp[m])

if __name__ == "__main__":
    solve()
```DP 阵列跟踪处理领域前缀后达到每个级别所需的最小净健康损失。 每个领域都会根据我们选择在那里战斗的敌人数量来提供一组过渡。 内循环逐渐累积伤害，因为再添加一个敌人会增加之前所有回合的伤害，增加其强度的总和，这是通过前缀累积捕获的。 

一个常见的实施陷阱是忘记治疗取决于完成领域后的级别，而不是每次杀戮后的级别。 这就是为什么每次转换都会应用一次治疗，而不是在内循环内部。 

另一个微妙之处是用 m 限制级别。 一旦我们达到 m 级，进一步的杀戮与状态转换无关，因此我们限制以避免不必要的计算。

 ## 边缘情况

 当一个领域包含一个非常强大的敌人和许多弱小的敌人时，就会出现严重的边缘情况。 该算法通过降序排序来处理此问题，确保先杀死强敌，因此其伤害仅施加一次，而不是跨回合重复施加。 

另一个边缘情况是玩家提早达到 m 级。 DP 会限制等级，因此任何进一步的杀戮都不会扩大状态空间。 即使 m 远小于生物总数，这也可以防止不必要的转换并确保正确性。 

最后一个边缘情况是高水平的治疗明显大于所造成的伤害。 DP 自然地利用了这一点，因为允许负有效成本转换，并且状态通过相应的较低所需初始健康值进行传播。
