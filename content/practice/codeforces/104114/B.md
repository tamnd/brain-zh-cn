 ## 解决方案
 ## 问题理解

 我们得到一个单位方形蛋糕，其中包含两种类型的点：巧克力片和草莓。 我们可以精确地画出一条穿过蛋糕的直线段。 切割后，我们选择线的一侧作为给孩子的那一块，但限制这块不能含有草莓。 在所有这些有效的选择中，我们希望最大化所选一侧的巧克力片数量。 

每个成分都是平面上的一个点，因此我们选择的几何对象是由一条线定义的半平面。 约束“不穿过成分”意味着该线不能穿过任何给定点。 同样，所有点必须严格位于该线的两侧之一。 

输出是一个整数：可以通过一条线与所有草莓点分开的巧克力点的最大数量。 

约束条件非常不对称：最多 50,000 个巧克力点，但最多 100 个草莓。 这立即表明，任何二次依赖于巧克力的解决方案都是不可行的，而二次依赖于草莓的解决方案可能仍然可以接受。 尝试评估由点对或所有巧克力分区引起的所有候选分隔线的简单方法将需要至少 O(n^2) 或更差的几何检查，这远远超出了 n 高达 50,000 的限制。 

当所有巧克力都位于每个有效草莓分离器方向的一侧时，就会出现微妙的边缘情况。 例如，如果草莓紧密地聚集在一起，并且巧克力围绕着它们，那么答案可能是全是巧克力。 相反，如果草莓“包裹”巧克力，则根本没有大的子集可以分离。 朴素推理的另一种失败模式是假设仅草莓的凸包就足够了； 事实并非如此，因为分隔线不需要接触草莓，只是为了避开它们。 

## 方法

 关键的几何重构是确定分离草莓的线的含义。 如果所有草莓都严格位于一条线的一侧，则这条线是有效的。 对于任何此类产品线，我们可以自由选择含有更多巧克力的一侧。 

因此，我们考虑的不是线条本身，而是它的方向。 每条有向线都定义一个半平面，我们想要一个方向，使所有草莓都位于同一个开放半平面中，同时在同一半平面中最大化巧克力。 

蛮力的想法是考虑由所有成分中的两点确定的每条可能的线。 每条这样的线都可以用作候选分隔符，我们可以测试哪一边是有效的并计算巧克力的数量。 这样的行有 O((n+m)^2) 条，每次检查的成本为 O(n)，因此在最坏的情况下这会变成三次方，这太慢了。 

主要观察结果是，约束完全来自草莓，而且只有 100 个。 任何有效的分隔线均由其围绕草莓组的角度位置确定。 如果我们固定一个参考点并扫过一条射线，则草莓按角度的排序是稳定的并且足够小以枚举关键转变。 

几何思想是固定切割线的方向，或者等效地固定法向量。 对于给定的方向，我们可以通过检查草莓的签名投影来确定是否所有草莓都位于一侧。 这将每个方向的有效性检查减少到 O(m)。 然后我们想要找到有效边包含最多巧克力的方向。

我们注意到，当分隔线与草莓相切或穿过两个草莓定义的角边界时，可行性的唯一相关变化就会发生，而不是迭代任意方向。 因此，候选方向可以减少到 O(m^2)，因为每对草莓都定义了一个临界方向，其中它们的相对顺序相对于扫描线翻转。 当 m ≤ 100 时，最多会产生大约 10,000 个方向，这是可以管理的。 

对于每个候选方向，我们计算与该方向一致的分离半平面，确定哪一侧包含所有草莓（如果有），然后计算同一半平面中有多少巧克力。 巧克力计数在运行时占主导地位，但在仔细实施的情况下，在可接受的性能下，在 10,000 个方向上获得 50,000 个点仍然是可行的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（所有行）| O((n+m)^3) | O(1) | O(1) | 太慢了|
 | 草莓的角度枚举 | O(m^2 (n+m)) | O(m^2 (n+m)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将每个草莓视为一个几何约束，必须严格位于最终线的同一侧。 这意味着分隔线必须定义一个不与草莓组相交的半平面。 
2. 对于每对有序的草莓，构造一个从穿过它们的线导出的候选分离方向。 该方向代表“有效侧”组合变化的潜在边界。 
3. 对于每个这样的方向，定义线的法线向量并确定线的哪一侧是候选安全半平面。 选择方向，使草莓始终位于一侧； 如果这是不可能的，请立即放弃该方向。 
4. 一旦建立了有效的半平面，迭代所有点并计算有多少巧克力严格位于该半平面内。 草莓不计入在内，因为其有效性保证被排除在外。 
5. 跟踪所有有效方向的最大巧克力数量。 

一个关键的微妙之处是方向的一致性。 对于给定的有向线，叉积的符号确定哪一侧被视为正。 如果我们翻转方向，则会获得相同的几何线，但半平面交换，因此我们必须始终对每个候选者的方向进行标准化。 

### 为什么它有效

 任何最佳的分离线都可以连续旋转，直到它变得关键，这意味着它接触或与两个草莓对齐，而不会违反可行性。 在此旋转过程中，每侧的点集仅在线穿过草莓或与一对草莓共线的离散事件中发生变化。 因此，仅检查这些事件定义的方向就足够了。 由于所有草莓最多都在 100 分之内，因此每个此类关键事件都对应一对，从而确保候选集的完整性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def side(x, y, a, b, c, d):
    return cross(a, b, x, y) >= cross(a, b, c, d)

def solve():
    n, m = map(int, input().split())
    pts = []
    for _ in range(n + m):
        x, y = map(float, input().split())
        pts.append((x, y))

    ch = pts[:n]
    st = pts[n:]

    if m == 0:
        print(n)
        return

    best = 0

    # iterate over candidate separating directions induced by strawberry pairs
    for i in range(m):
        for j in range(i + 1, m):
            xi, yi = st[i]
            xj, yj = st[j]

            dx = xj - xi
            dy = yj - yi

            # normal vector candidates: perpendicular directions
            # we test one orientation; flipping handled implicitly by max side choice
            nx, ny = -dy, dx

            # skip degenerate
            if nx == 0 and ny == 0:
                continue

            # decide which side strawberries lie on (using i as reference side)
            # we want st[k] all on same side; pick side based on majority consistency
            def ok(sign):
                for xk, yk in st:
                    v = cross(nx, ny, xk - xi, yk - yi)
                    if sign * v < 0:
                        return False
                return True

            valid = False
            for sign in [1, -1]:
                if ok(sign):
                    valid = True
                    break

            if not valid:
                continue

            # count chocolates on that side
            for xk, yk in ch:
                v = cross(nx, ny, xk - xi, yk - yi)
                if v * sign >= 0:
                    best += 1

            best = max(best, best)

    print(best)

if __name__ == "__main__":
    solve()
```该实现将巧克力和草莓分开，然后迭代草莓对来定义候选方向。 对于每个方向，使用垂直变换计算法向量。 方向经过测试，以便所有草莓都位于生产线的同一侧。 

这里的一个常见陷阱是混淆了叉积中使用的参考点。 表达式`(xk - xi, yk - yi)`锚定相对于一对中的一个草莓的所有检查，这已经足够了，因为叉积仅确定相对侧面。 另一个微妙的问题是确保严格的分离； 叉积中的相等对应于共线性，这是问题所不允许的，因此在候选生成中必须将这些情况视为无效或避免。 

最终计数聚集了满足所选半平面条件的巧克力。

 ## 边缘情况

 一个关键的边缘情况是草莓与候选分隔线共线。 在这种配置中，简单的叉积检查可能会错误地将边界点视为有效。 例如，如果巧克力正好位于穿过两个草莓的线上，则符号变为零并且必须被排除，否则算法可能会计算出无效配置。 实施必须将平等视为不允许的。 

当所有草莓几乎共线时，就会出现另一种边缘情况。 在这种情况下，许多候选方向会折叠成类似的半平面，并且可能会发生重复评估。 该算法仍然有效，因为它独立地处理每一对，但如果不小心，这可能会导致重复计数，除非每次迭代都正确重置结果。 

最后，当草莓在所有巧克力周围形成凸包络时，每个有效的半平面都受到高度约束。 该算法仍然枚举所有方向，但大多数都会很快通过可行性测试，这对于性能至关重要。
