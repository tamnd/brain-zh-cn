 ## 解决方案
 ## 问题理解

 我们得到一个基本字符串`s`。 每天，Momo 不会在内部对其进行修改，而是通过连接原始字符串的副本来构建更长的字符串`s`。 第一天之后，字符串正好是`s`。 第2天后，就变成了`s + s`。 第 k 天之后，就变成`s`连续重复k次。 

波波还有一根绳子`t`。 问题是确定最小的天数 k 使得`t`可以作为重复形成的字符串的子序列找到`s`正好k次。 

子序列意味着我们可以从重复的字符串中删除字符而不改变顺序，并且我们希望能够获得`t`。 

关键的困难在于我们没有被问到是否`t`是固定字符串的子序列，但重复次数最少`s`需要它才能成为可能。 

约束条件允许两者`s`和`t`最多 500,000 个字符。 这立即排除了任何显式构造重复字符串的方法。 即使重复两次最大大小的字符串也已经超出了内存限制，并且不可能得到答案。 

我们还需要小心这样一个事实：`t`可能需要多次重复扫描`s`。 每天一次简单的子序列检查将模拟多达 k 次传递`s`，给出二次或更差的行为。 

一些边缘情况很重要。 

如果`t`包含一个不存在于中的字符`s`，那么一般来说是不可能的，但是声明保证了答案存在，所以排除了这种情况。 

如果`t`已经是`s`，答案是1。 

如果字符为`t`分布使得匹配强制重新启动扫描`s`很多时候，答案可能很大，但我们必须在不显式构建重复字符串的情况下检测到这一点。 

## 方法

 直接的暴力策略就是日复一日地模拟。 对于第 k 天，我们在概念上构建`s`重复k次并检查是否`t`是使用两指针扫描的子序列。 此子序列检查与所构造字符串的长度呈线性关系，因此每天的时间复杂度为 O(k·|s| + |t|)。 

在最坏的情况下，k 本身可以与|t|一样大，例如当`t`每个副本仅匹配一个字符`s`。 This leads to a total complexity around O(|s| · |t|), which is far too slow for 5 · 10^5 limits.

 The key observation is that we never need to build repeated strings explicitly. Instead, we simulate the subsequence matching greedily while cycling through`s`。 

我们扫描`t`从左到右并保持一个指针`s`。 当我们无法匹配下一个字符时`t`在当前扫描中`s`，我们“环绕”到下一个副本`s`，这恰好对应于移动到第二天的重复边界。 每次我们重新开始扫描`s`，我们增加日计数器。 

这是有效的，因为子序列匹配仅取决于相对顺序，并且重复`s`只是给了我们另一个相同的扫描窗口。 

为了提高效率，我们对每个字符的位置进行预处理`s`这样我们就可以使用数组在 O(log σ) 或 O(1) 中跳转到下一个有效的出现位置。 然而，一个更简单的 O(n + m) 贪婪算法通过扫描来工作`s`反复使用指针重置。 

该过程相当于反复遍历`s`消费时`t`。

 ## 算法演练

 我们模拟匹配`t`作为重复副本的子序列`s`无需构建它们。 

1. 初始化一个指针`i = 0`对于字符串`t`和一个柜台`days = 1`，表示我们当前位于第一个副本中`s`。 

我们还维护一个指针`j = 0`用于扫描`s`。 
2. 虽然`i < len(t)`,尝试匹配`t[i]`通过扫描`s`从位置开始`j`。 
3. 移动`j`向前通过`s`直到`s[j] == t[i]`或者我们到达了终点`s`。 

此步骤表示尝试在当前重复中查找下一个匹配项。 
4. 如果我们找到匹配项`s[j] == t[i]`，推进两个指针（`i += 1`,`j += 1`）并继续。 

这保留了后续顺序。 
5. 如果我们到达终点`s`没有找到匹配项，则递增`days`， 重置`j = 0`，并继续扫描`s`从一开始。 

这对应于进入下一个重复副本`s`。 
6. 重复直到所有字符`t`是匹配的。 

最终值`days`是所需的最小重复次数。 

### 为什么它有效

 在任何时刻，该算法都在有效地模拟对无限串联的遍历`s`。 每次我们精疲力尽的时候`s`没有完成`t`，我们被迫移动到下一个相同的块。 由于每个块都是相同的，因此唯一重要的状态是内部的当前位置`s`和当前索引`t`。 贪婪扫描保证了每个字符`t`在当前或下一个副本中最早可能的位置进行匹配`s`，所以我们绝不会在不必要的情况下过度使用块。 这保证了最小的重置次数，这恰好对应于最小天数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    n = len(s)

    i = 0
    j = 0
    days = 1

    while i < len(t):
        if j == n:
            days += 1
            j = 0

        if s[j] == t[i]:
            i += 1
            j += 1
        else:
            j += 1

    print(days)

if __name__ == "__main__":
    solve()
```该代码维护两个指针：一个指向`t`比当前副本多一`s`。 当扫描的`s`完成后，我们增加日计数器并重新开始扫描。 关键的实现细节是我们从不构建重复的字符串，并且指针`j`充当当前重复中的虚拟位置。 

一个微妙的点是我们必须重置`j`恰好当它到达`len(s)`，而不是当匹配失败时，因为不匹配仍应在同一重复内推进扫描。

 ## 边缘情况

 一个重要的边缘情况是当`t`需要重复进行全面扫描`s`因为匹配只发生在每个副本的末尾附近。 

例如，如果`s = abcd`和`t = dddd`，每个副本`s`在最后一个字符处仅提供一个可用的匹配。 该算法重复扫描到末尾，递增`days`，然后继续，生成等于发生次数的正确天数。 

另一个边缘情况是当`t`相比之下非常短`s`， 例如`s = abcde...`和`t = single character`。 该算法在第一次扫描时立即匹配并且从不递增`days`，正确返回1。 

最后，如果`s`是一个重复的字符，例如`aaaaa`和`t`也是全部`a`，算法在必要时不会重置，天数等于`t`，符合最小重复要求。
