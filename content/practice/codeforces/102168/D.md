 ## 解决方案
 ## 问题理解

 我们有一个字符串`s`长度`n`。 对于每个职位`i`，Vasya写入精确删除位置处的字符得到的字符串`i`。 所有结果字符串都有长度`n - 1`，任务是数出其中有多少个`n`字符串实际上是不同的。 

输入包含一个小写拉丁字符串。 它的长度在 2 到 200,000 之间，因此算法执行的工作量与`n^2`太贵了。 如果有 200,000 个位置，即使是一个简单的二次循环，在最坏的情况下也需要大约 400 亿次迭代，这无法满足 2 秒的限制。 我们需要一个线性或近线性的解决方案。 

微妙之处在于两个不同的删除位置可以产生完全相同的字符串。 例如，对于`aaa`，删除三个字符中的任何一个都会给出`aa`，所以答案是 1 而不是 3。在这种情况下，简单计算删除位置的粗心解决方案将会失败。 

另一个边界情况是`ab`。 删除第一个字符给出`b`，同时删除第二个给出`a`，所以答案是 2。如果实现意外地将每对相邻位置视为等效，则会错误地返回 1。 

一个更长的例子是`aabb`。 从第一个字符中删除任一字符`aa`给出`abb`，同时从最后一个字符中删除任一字符`bb`给出`aab`。 答案是 2。字符的相等性在两个删除位置之间的整个间隔中都很重要，而不仅仅是在两个端点处。 

## 方法

 直接的方法是为每个可能的删除位置构造结果字符串，并将所有结果字符串放入一个集合中。 这是正确的，因为每个生成的字符串都准确地代表 Vasya 的某一天，并且该集合会删除重复项。 然而，构建一个结果需要花费`O(n)`，并且有`n`可能的删除，给出`O(n^2)`时间。 为了`n = 200000`，在考虑字符串和集合开销之前，大约有 400 亿个字符操作。 

有用的观察是我们实际上不需要构造任何这些字符串。 考虑两个删除位置`i < j`。 之前的位置`i`，两个结果字符串都包含完全相同的前缀。 位置后`j`，两者包含完全相同的后缀。 唯一可能不同的部分是从`i`通过`j`。 

正在删除`i`树叶```
s[i+1] s[i+2] ... s[j]
```从该间隔开始，同时删除`j`树叶```
s[i] s[i+1] ... s[j-1]
```为了使这两个字符串相等，区间中的每个字符`s[i..j]`必须是相同的。 即使有一个字符不同，两个结果字符串的相应位置也会不同。 

这给出了一个非常简单的等价规则：删除位置`i`和`j`当它们之间的每个字符都相等时，会生成完全相同的字符串。 换句话说，当删除该串中的一个字符时，属于同一字符最大串的所有位置都会产生相同的结果。 

为了`aabb`，运行次数是`aa`和`bb`，因此有两个不同的结果字符串。 为了`abca`，每个角色都有自己的运行方式，因此有四种不同的结果。 为了`zzz`，只有一次运行，因此每次删除都会产生相同的字符串。 

因此，答案就是相同字符的最大连续运行次数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | 最坏情况下的 O(n²) | 太慢了 |
 | 计算相同字符的运行次数 | O(n) | O(1) 辅助空间 | 已接受 |

 ## 算法演练

 1.读取字符串`s`并从 1 开始回答。`n >= 2`，至少存在一个删除结果，第一个字符开始第一次运行。 
2. 从第二个字符到末尾扫描字符串。 每当`s[i]`不同于`s[i - 1]`，新的最大运行开始，因此增加答案。 
3. 忽略位置`s[i] == s[i - 1]`。 它们属于同一运行，并且从该运行中删除任何一个字符都会得到相同的结果字符串。 
4. 打印运行次数。 

### 为什么它有效

 将字符串划分为相同字符的最大串。 假设两个删除位置属于同一运行。 它们之间的每个字符都是相同的，因此将删除从一个位置移动到另一个位置不会改变结果字符串。 因此，一次运行中的所有位置都对应于一个不同的结果。 

现在假设两个位置属于不同的运行。 它们之间存在两个连续字符不同的边界。 两个删除结果在该边界处不同，因为一个结果将边界一侧的字符移动，而另一个则不移动。 因此，不同运行的位置不能产生相同的字符串。 

因此，对于每个最大等字符运行，恰好有一个不同的结果字符串，对这些运行进行计数即可给出所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_string(s: str) -> int:
    answer = 1

    for i in range(1, len(s)):
        if s[i] != s[i - 1]:
            answer += 1

    return answer

def main() -> None:
    s = input().strip()
    print(solve_string(s))

if __name__ == "__main__":
    main()
```这`solve_string`函数直接实现运行计数算法。 初始值`answer = 1`有效，因为输入长度至少为 2，因此字符串始终至少有一个游程。 

循环从索引 1 开始，因为索引 0 没有可比较的前一个字符。 每一次改变从`s[i - 1]`到`s[i]`开始新的运行并贡献一个新的不同删除结果。 

删除后得到的字符串不需要构造，也不需要设置。 Python 整数对于这个答案来说也绰绰有余，因为它最多`n`，只有20万。 

这`strip()`调用删除标准输入提供的换行符。 由于该字符串仅包含小写拉丁字母，因此不存在可能被意外删除的有意义的空格。

 ## 边缘情况

 对于`aa`，算法开始于`answer = 1`。 在索引 1 处，当前字符也是`a`，所以答案仍然是 1。两种可能的删除都会产生`a`，这确认了最小尺寸等字符情况的处理。 

为了`ab`，初始答案为1，在索引1处比较发现`b != a`，将答案增加到2。两个删除结果是`b`和`a`，所以它们确实不同。 

为了`aaaa`，扫描从未看到与其前身不同的字符。 答案仍然是 1，与删除四个位置中的任何一个都会产生的事实相匹配`aaa`。 

为了`aabbbaa`，扫描看到转变`a -> b`和`b -> a`。 从 1 开始，这两个转换产生的答案为 3。运行是`aa`,`bbb`， 和`aa`，并且每次运行都对应于一个不同的字符串。 

对于最大长度交替字符串`abab...ab`，每个相邻对都不同。 第一个位置之后的每个位置的答案都会递增，产生 200,000。 这会检查答案的上限以及循环中是否存在差一错误。 

整个解决方案背后的关键边缘情况是同一等字符运行中的一对删除位置。 为了`aabb`，从第一个字符中删除任一字符`aa`产生`abb`。 该算法仅对整个运行进行一次计数。 当从第一轮移动到第二轮时，角色从`a`到`b`，因此答案增加到 2，完全匹配两个不同的结果字符串。
