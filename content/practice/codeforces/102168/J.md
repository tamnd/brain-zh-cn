 ## 解决方案
 ## 问题理解

 我们有一个排列`p`包含来自的每个整数`1`到`n`正好一次。 在每一轮中，第一个玩家的名字`a`, 第二个玩家名字`b`， 和`a`和`b`保证是不同的。 获胜者是号码在排列中出现较早的玩家。 

例如，如果```
p = [4, 2, 5, 1, 3]
```那么位置`2`是`2`，而位置`3`是`5`。 一轮`(2, 3)`，第一个玩家获胜，因为`2`发生得更早。 为了`(3, 2)`，第二个玩家获胜。 

输入首先给出排列，然后是`q`独立查询。 对于每个查询，我们需要打印`First`如果第一个数字出现在排列中较早的位置，否则`Second`。 

约束达到`n = 200000`和`q = 200000`。 扫描每个查询的排列的解决方案最多可以执行`n * q = 40,000,000,000`最坏情况下的比较，远远超出了两秒的极限所能容忍的范围。 我们需要对排列进行预处理，以便可以在恒定时间内回答每个查询。 一个`O(n + q)`解决方案非常合适。 

有几种边缘情况可能会导致粗心的实施失败。 首先，中奖号码可以位于第一个或最后一个位置。 为了```
2
2 1
1
1 2
```输出是```
Second
```因为`2`处于位置`1`和`1`处于位置`2`。 意外地不一致地使用从零开始和从一开始的位置的实现可以逆转这种比较。 

查询中两个数字的顺序也很重要。 和```
3
2 3 1
2
2 1
1 2
```输出是```
First
Second
```该对在两轮中都包含相同的两个值，但玩家交换了它们。 比较值本身而不是它们的位置会给出错误的结果。 

重复查询是另一个有用的例子。 为了```
4
3 1 4 2
3
1 2
1 2
2 1
```输出是```
First
First
Second
```预处理由每个查询共享，因此当同一对再次出现时没有理由执行任何额外的工作。 

最后，短语“全等值”无法描述此问题的有效测试。 排列包含不同的值，并且每个查询显式包含两个不同的值。 最接近的有意义的压力情况是多次重复相同的有效查询，这测试实现是否意外地在轮次之间改变状态。 

## 方法

 直接的解决方案是通过搜索排列来处理每个查询，直到找到两个请求的值。 一旦知道两个位置，我们就会对它们进行比较。 这是正确的，因为获胜者完全由首先出现的值来定义。 

问题在于重复搜索。 在最坏的情况下，查询可能会迫使我们在找到其值之前检查几乎整个排列。 和`q = 200000`查询和`n = 200000`，最坏情况的工作量约为`40,000,000,000`阵列检查。 即使单次检查很便宜，数百亿次的操作也无法兼容时间限制。 

关键的观察是轮次之间的排列永远不会改变。 我们不断地问关于固定数组的同一类问题：“值在哪里？`x`发生吗？”由于每个值都只出现一次，因此我们可以提前回答每个此类问题。

 构建逆排列`pos`， 在哪里`pos[x]`存储该值所在的位置`x`发生在`p`。 之后，查询`(a, b)`变成只有比较```
pos[a] < pos[b]
```如果表达式为真，则第一个玩家获胜。 否则，第二个玩家获胜。 

这将问题从重复搜索数组改为执行一次线性预处理，然后执行恒定时间查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 最坏情况 O(nq) | O(1) 额外 | 太慢了 |
 | 最佳| O(n + q) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读`n`和排列`p`。 所有轮次的排列都是固定的，因此有关位置的所有有用信息都可以计算一次。 
2. 创建数组`pos`尺寸的`n + 1`。 对于每个索引`i`和价值`x = p[i]`， 店铺`pos[x] = i`。 索引处的额外元素`0`未使用，因为排列值的范围为`1`到`n`。 
3.读取查询数量`q`。 对于每个查询，读取两个值`a`和`b`。 
4. 比较`pos[a]`和`pos[b]`。 如果`pos[a] < pos[b]`，第一个玩家的数字出现较早，因此输出`First`。 否则输出`Second`。 
5. 收集答案并一起打印。 当最多有 1 个输出字符串时，构建一个输出字符串可以避免不必要的重复输出操作`200000`查询。 

### 为什么它有效

 中心不变量是经过预处理后，`pos[x]`正是值的位置`x`在原来的排列中。 由于排列只包含每个值一次，因此每个查询值都只有一个这样的位置。 对于查询`(a, b)`，当发生以下情况时，第一个玩家获胜`a`是在发生之前`b`，这正是条件`pos[a] < pos[b]`。 因此，每个产生的答案都符合游戏规则。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    pos = [0] * (n + 1)

    for i, x in enumerate(p):
        pos[x] = i

    q = int(input())
    ans = []

    for _ in range(q):
        a, b = map(int, input().split())

        if pos[a] < pos[b]:
            ans.append("First")
        else:
            ans.append("Second")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```这`pos`数组是整个优化。 在预处理循环期间，`i`是一个从零开始的 Python 索引，但这不会导致问题，因为只有相对顺序很重要。 如果`pos[a] < pos[b]`， 然后`a`无论位置是从零还是从一开始编号，都会较早出现。 

数组有长度`n + 1`这样值本身就可以直接用作索引。 这避免了额外的转换，例如`x - 1`并且使得查询代码特别简单。 

查询条件不需要相等分支。 输入保证`a != b`，并且排列只包含每个值一次，所以`pos[a]`和`pos[b]`永远不可能平等。 

Python 中不可能出现整数溢出，最大存储索引仅为`199999`。 

答案已累积在`ans`并在最后写一次。 和`200000`查询，这比调用更好`print`分别为每个结果。 

## 工作示例

 提供的样本包含排列```
p = [2, 3, 1]
```所以它的逆表示是`pos[1] = 2`,`pos[2] = 0`， 和`pos[3] = 1`。 

| 查询 |`a`|`b`|`pos[a]`|`pos[b]`| 结果 |
 | ---| ---| ---| ---| ---| ---|
 | 1 | 1 | 2 | 2 | 0 | 第二 |
 | 2 | 1 | 3 | 2 | 1 | 第二 |
 | 3 | 2 | 1 | 0 | 2 | 第一|
 | 4 | 2 | 3 | 0 | 1 | 第一|

 这说明了为什么一旦建立了逆排列，实际数值就无关紧要了。 例如，`1 < 3`， 但`1`仍然输给`3`因为`1`发生在排列的后面。 

第二个例子是```
4
3 1 4 2
3
1 2
1 4
2 1
```逆排列是`pos[1] = 1`,`pos[2] = 3`,`pos[3] = 0`， 和`pos[4] = 2`。 

| 查询 |`a`|`b`|`pos[a]`|`pos[b]`| 结果 |
 | ---| ---| ---| ---| ---| ---|
 | 1 | 1 | 2 | 1 | 3 | 第一|
 | 2 | 1 | 4 | 1 | 2 | 第一|
 | 3 | 2 | 1 | 3 | 1 | 第二 |

 第三个查询特别有用，因为它具有与第一个查询完全相同的两个值，但顺序相反。 这是从玩家角度进行的比较，所以交换一下`a`和`b`交换获胜者。

 和`n, q <= 200000`，该算法仅执行数十万次数组操作和比较。 这`O(n)`内存使用量也轻松控制在 256 MB 限制之内。

## 边缘情况

 考虑最小输入```
2
2 1
1
1 2
```预处理存储`pos[2] = 0`和`pos[1] = 1`。 查询比较`pos[1] = 1`和`pos[2] = 0`，所以条件为假，答案为`Second`。 这捕获了比较值而不是位置的实现。 

对于反向查询顺序，请使用```
2
2 1
1
2 1
```现在`pos[2] = 0 < pos[1] = 1`，所以输出是`First`。 排列没有改变。 只是玩家分配的号码发生了变化，这就是输出发生变化的原因。 

对于排列每个极端的值，考虑```
5
5 1 4 2 3
2
1 5
5 3
```职位是`pos[1] = 1`,`pos[5] = 0`， 和`pos[3] = 4`。 第一个查询给出`Second`因为`5`是在之前`1`。 第二个给出`First`因为`5`是在之前`3`。 这验证了第一个和最后一个位置是否被正常处理。 

对于重复查询，请考虑```
4
3 1 4 2
4
1 2
1 2
2 1
2 1
```存储的位置是`pos[1] = 1`和`pos[2] = 3`。 每一个`(1, 2)`查询产生`First`，而每一个`(2, 1)`查询产生`Second`。 由于算法永远不会修改`pos`，每次重复都会收到相同的正确答案。 

边界值`n`也可以直接用作索引，因为`pos`有尺寸`n + 1`。 例如，当`n = 200000`，值`200000`存储在`pos[200000]`没有任何特殊情况。 这避免了仅分配的常见差一错误`n`元素，同时仍然按值本身进行索引。
