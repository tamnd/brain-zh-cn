 ## 解决方案
 ## 问题理解

 我们有两个非空小写字符串，`s`和`t`。 在一次操作中，我们可以选择任意两个位置`s`并反转它们之间的整个子字符串。 我们可以执行该操作任意次数，包括零次。 任务是确定是否`s`可以准确地转化为`t`。 

关键问题不在于要执行哪些单独的反转，而是通过重复的反转可以产生哪些角色的重新排列。 由于两个字符串最多包含 200,000 个字符，因此检查许多可能的反转序列的算法无法工作。 由于有两秒的限制，预期的解决方案需要在字符串长度上基本上是线性的。 二次算法在最大规模下已经需要大约 400 亿次基本迭代，这远远超出了实际情况。 

第一个边缘情况的长度不同。 例如，`s = "abcd"`和`t = "abc"`必须产生`NO`。 反转永远不会改变字符数，因此任何仅比较字符频率而不首先考虑长度的方法都需要明确处理这个问题。 

第二个边缘情况是重复字符。 为了`s = "xxx"`和`t = "yyy"`，答案是`NO`，即使两个字符串的长度相同。 仅检查长度的粗心解决方案会接受它。 性格的多样性很重要。 

第三种边缘情况是字符串不必相等或可以通过单次反转获得。 为了`s = "abac"`和`t = "acba"`，答案是`YES`。 转变可以通过多次逆转来实现，因此测试是否`t`正好是一个反向子串`s`是不够的。 

第四个边缘情况是已经等于目标的字符串。 例如，`s = "abc"`和`t = "abc"`必须产生`YES`，因为允许执行零运算。 假设至少需要一次反转的实现可以拒绝这种有效情况。 

## 方法

 直接的暴力方法会将字符的每种可能的排列视为候选可达状态。 对于每个状态，我们可以尝试所有可能的逆转并继续探索，直到`t`已找到或已用尽所有可到达的安排。 这是正确的，因为每个合法操作都被明确表示，但它很快就会变得不可用。 和`n`可以有不同的字符`n!`不同的排列，甚至检查一种排列`t`成本`O(n)`。 因此，完整的基于排列的搜索至少需要`O(n · n!)`工作，还有额外的`O(n^2)`如果每个状态都明确检查所有可能的反转间隔，则为因子。 

有用的观察来自于考虑最小可能的逆转。 如果我们反转长度为 2 的子串，位置`i`和`i + 1`只需交换他们的角色即可。 换句话说，允许的操作包括相邻交换。 

相邻交换足以产生字符串的每个排列。 我们可以一次将任何所需的角色移动一个位置，直到它到达目标位置，对每个位置重复此过程。 因此，重复的子串反转可以重新排列中的字符`s`以完全任意的方式。 

一旦可以进行任意排列，原始字符的确切顺序就不再重要。 唯一不变的是每个字符出现的次数。 一个转变从`s`到`t`当两个字符串的每个小写字母具有相同的长度和相同的频率时，恰好存在。 

因为字母表只包含 26 个小写字母，所以我们甚至不需要通用字典。 我们可以保留两个 26 个计数器的数组并比较它们。 这给出了一个简单的线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n · n!)`至少 |`O(n)`存储状态，访问状态可能呈指数增长 | 太慢了 |
 | 最佳|`O(n)`|`O(1)`| 已接受 |

 ## 算法演练

 1. 阅读`s`和`t`并比较它们的长度。 如果长度不同，则打印`NO`立即，因为反转永远不会改变持仓数量。 
2. 创建一个包含 26 个计数器的数组`s`另一个由 26 个计数器组成的数组`t`。 指数`0`代表`'a'`， 指数`1`代表`'b'`， 等等。 
3. 扫描`s`并增加与每个字符对应的计数器。 做同样的事情`t`。 这准确记录了每个字符串包含哪些字符的多集。 
4. 比较两个频率阵列。 如果每个计数都相等，则打印`YES`; 否则打印`NO`。 

此频率测试足够的原因是长度二反转为我们提供了相邻交换。 由于任意相邻交换生成每个排列，因此可以达到具有相同字符多重集的任何排序。 

### 为什么它有效

 每个操作都会保留多组字符，因此不同的频率永远不能相互转换。 相反，假设`s`和`t`具有相同的字符频率。 由于允许相邻交换，我们可以重新排列`s`进入其字符的任何排列。 我们可以构建`t`通过使用相邻交换将所需字符的出现移动到每个目标位置，从左到右。 重复的子串反转可以执行这些交换，所以`t`是可达的。 因此频率条件既是必要的又是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    if len(s) != len(t):
        print("NO")
        return

    cnt_s = [0] * 26
    cnt_t = [0] * 26

    for ch in s:
        cnt_s[ord(ch) - ord('a')] += 1

    for ch in t:
        cnt_t[ord(ch) - ord('a')] += 1

    print("YES" if cnt_s == cnt_t else "NO")

if __name__ == "__main__":
    solve()
```第一个检查在任何字符处理之前处理长度边界。 这在逻辑上是必要的，而且对于不可能的输入来说稍微便宜一些。 

这两个数组正好有 26 个条目，因为输入字母仅限于小写英文字母。 表达式`ord(ch) - ord('a')`将每个字符映射为 0 到 25 之间的整数。 

比较`cnt_s == cnt_t`同时检查所有字符的多重性。 无需比较位置，因为反转可以任意改变顺序。 

Python 中不可能出现整数溢出，最大计数器也只有 200,000。 琴弦本身也很适合记忆。

    old_stdout = sys.stdout

 ## 边缘情况

 对于不同的长度，请考虑`s = "abcd"`和`t = "abc"`。 算法比较`4`和`3`，立即打印`NO`，并且从不尝试比较它们的字符频率。 这是正确的，因为每次反转都会准确地保留长度。 

对于具有不同重数的重复字符，考虑`s = "aabb"`和`t = "abac"`。 两个字符串的长度均为四，因此长度测试通过。 的频率`a`两个字符串中都是两个，但是`s`包含两个`b`字符同时`t`包含一个`b`和一个`c`。 数组在这些位置不同，所以结果是`NO`。

对于已经相等的字符串，请考虑`s = "abc"`和`t = "abc"`。 长度匹配并且所有三个字符计数匹配，因此结果是`YES`。 这对应于使用零操作，这是允许的。 

对于尽可能小的字符串，`s = "a"`和`t = "b"`根本无法改变，因为没有一对不同的头寸可以执行有意义的逆转。 它们的频率不同，因此算法返回`NO`。 为了`s = "a"`和`t = "a"`，频率匹配并且算法返回`YES`。
