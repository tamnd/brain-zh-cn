 ## 解决方案
 ## 问题理解

 有`n`比赛按时间顺序排列。 比赛用`i`,`a[i]`是参与其中获得的评级提升。 参加比赛后`i`，基里尔必须跳过下一个`b[i]`比赛，所以他最早可以参加的比赛是在`i`是`i + b[i] + 1`。 

任务是选择一组恢复间隔不重叠的比赛，最大化它们的总和`a[i]`价值观。 自从`a[i]`可以是负数，空的选择也是相关的：基里尔可以简单地参加不参加任何比赛并获得收益`0`。 

和`n <= 200000`， 一个`O(n^2)`解决方案太慢了。 在最坏的情况下，它的性能约为`200000^2 / 2 = 20,000,000,000`状态转换，不能满足 2 秒的限制。 我们需要一种接近线性时间的算法。 

的价值观`a[i]`可以达到`10^9`无论是哪个方向，答案都可以包含来自许多竞赛的贡献。 32 位整数是不够的：答案可能是`2 * 10^14`在幅度上。 Python 整数会自动处理这个问题，而 C++ 等语言则需要`long long`。 

有几种边界情况可能会导致直接实现错误。 如果只有一场比赛，例如```
1-10 0
```答案是`0`， 不是`-10`，因为参与是可选的。 如果`b[i] = 0`，下一场比赛立即可用。 例如，```
25 07 0
```有答案`12`，所以治疗`b[i]`就好像它包括比赛一样`i + 1`会错误地禁止第二次比赛。 

另一个边界是当恢复期超出整个剩余序列时。 为了```
210 5100 0
```答案是`100`。 在第 1 场比赛之后，没有剩余可用的比赛，但这并不意味着第 1 场比赛是强制性的，也不会优先于第 2 场比赛。 

最后，消极的竞争不能迫使我们接受它们。 为了```
3-5 0-2 0-7 0
```答案是`0`。 如果 DP 初始化为负无穷大，但没有明确表示不参加任何比赛的可能性，则可能会默默地产生否定答案。 

## 方法

 一个简单的解决方案会考虑所有可能的最后一场比赛。 假设我们决定那场比赛`i`是我们参加的最后一场比赛。那么所有较早选择的比赛必须在`i`，我们可以递归地枚举它之前的所有有效子集。 这是正确的，因为每个有效的时间表都有明确定义的最后一场比赛，但子集的数量是指数级的，因此这种方法甚至早于`n = 200000`。 

我们可以通过动态规划使暴力破解的想法更加结构化。 让`dp[i]`是仅使用第一个即可获得的最大评级提升`i`比赛。 处理比赛时`i`，恰好有两种可能性。 我们跳过它，离开`dp[i - 1]`。 或者我们参加它，在这种情况下，之前选择的比赛最多只能是`b[i] + 1`之前的职位`i`。 如果第一个`i`比赛编号从`1`，恢复期之前的最后一场比赛是`i - b[i] - 1`。 

因此通过参加比赛获得的价值`i`是`a[i] + dp[i - b[i] - 1]`。 

关键的观察是`dp`已经包含每个可能的前缀的最佳答案。 我们不需要检查个别较早的时间表。 禁区之前的整个历史可以用一个数字来概括。 

这给出了重现`dp[i] = max(dp[i - 1], a[i] + dp[max(0, i - b[i] - 1)])`。 

这`max(0, ...)`处理竞赛案件`i`迫使我们走到数组的开头之前。 递归检查每个竞赛一次，因此总工作是线性的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) 递归深度 | 太慢了 |
 | 前缀 DP | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 创建`dp`在哪里`dp[i]`代表从第一次获得的最佳评级增加`i`比赛。 放`dp[0] = 0`，因为在考虑任何比赛之前，增益为零。 
2. 从左到右处理比赛。 比赛用`i`，首先考虑跳过它。 在这种情况下最好的结果正是`dp[i - 1]`。 
3.如果我们参加比赛`i`，我们必须跳过下一个`b[i]`比赛。 禁止间歇期之前的比赛是`i - b[i] - 1`。 因此，最佳兼容的早期结果是`dp[max(0, i - b[i] - 1)]`。 
4.添加`a[i]`到那个兼容的前缀结果。 这给出了最佳时间表，其选择的比赛包括`i`。 
5. 将较大的跳过和参与案例存储在`dp[i]`。 处理完所有比赛后，`dp[n]`是最大可能的评级增加。 

### 为什么它有效

 考虑第一个中的最佳时间表`i`比赛。 如果不包含竞赛`i`，其值最多为`dp[i - 1]`， 和`dp[i - 1]`代表了此类时间表中最好的。 如果它确实包含竞赛`i`，所有其他选定的比赛都必须属于第一个`i - b[i] - 1`比赛。 根据定义`dp`，最兼容的早期时间表具有价值`dp[max(0, i - b[i] - 1)]`。 添加`a[i]`给出了最好的时间表，其中包括`i`。 这两种情况涵盖了每个有效的时间表，因此取其最大值可以为每个前缀提供真正的最佳值。 通过归纳法`i`,`dp[n]`是最优的。 

## Python 解决方案```python
Pythonimport sysinput = sys.stdin.readline

def solve():    n = int(input())
    dp = [0] * (n + 1)
    for i in range(1, n + 1):        a, b = map(int, input().split())
        previous = i - b - 1        if previous < 0:            previous = 0
        take = a + dp[previous]        skip = dp[i - 1]
        dp[i] = max(skip, take)
    print(dp[n])

if __name__ == "__main__":    solve()
```数组`dp`使用一个额外的位置，以便`dp[0]`自然代表空前缀。 比赛时`i`,`previous = i - b - 1`是可以与竞赛一起使用的最大前缀`i`。 

减一是主要的索引细节。 如果`b = 0`, 竞赛`i - 1`是允许的，因此前缀必须以`i - 1`。 该公式准确给出`i - 0 - 1 = i - 1`。 如果`b = 1`, 竞赛`i - 1`必须被跳过，所以可用的前缀结束于`i - 2`。 

什么时候`previous`是负数，根本没有任何比赛可以先于`i`， 和`dp[0] = 0`代表了这种情况。 Python 的任意精度整数还可以安全地处理高达大约`200000 * 10^9`。 

输入被处理为`sys.stdin.readline`，这避免了将整个输入重复分割成一个大的标记列表的开销。

 ## 边缘情况

 ### 一场消极比赛

 对于```
1-10 0
```初始状态是`dp[0] = 0`。 参加唯一的比赛可以得到`-10`，同时跳过它给出`0`， 所以`dp[1] = 0`。 该算法从不假设必须至少选择一场比赛。 

### 无恢复期

 对于```
25 07 0
```竞赛 1 有`previous = 0`, 给予`dp[1] = 5`。 竞赛 2 有`previous = 1`， 因为`2 - 0 - 1 = 1`。 其取值为`7 + dp[1] = 12`，所以答案是`12`。 这正是以下情况下所需的边界行为：`b[i] = 0`。 

### 超越开始的恢复

 对于```
210 5100 0
```竞赛 1 有`previous = -5`，它被钳位到`0`。 接受它给出`10`。 竞赛 2 有`previous = 1`, 给予`100 + dp[1] = 110`因为它本身的回收价值为零。 因此答案实际上是`110`，因为比赛 2 可以在比赛 1 之后进行。`b[1]`只影响比赛 1 之后的内容，而不影响比赛 2 之前的内容。这种区别正是 DP 回顾正在考虑的比赛的原因。 

### 所有值为负数

 对于```
3-5 0-2 0-7 0
```每一个`take`值为负数，而`skip`遗迹`0`。 因此，整个阵列中的 DP 保持为零。 这解决了增加评级是可选的这一事实。 

### 非常大的正值

 假设许多兼容的比赛都有`a[i] = 10^9`。 和`200000`比赛总人数可达`2 * 10^14`。 在此规模下，递归本身不会改变，但使用 32 位整数的实现会溢出。 Python 的整数类型避免了这个问题，因此相同的递归对于整个输入范围仍然有效。
