 ## 解决方案
 ## 问题理解

 我们有一系列`n`显示值。 最初，按钮`i`节目`a[i]`，我们希望它显示`b[i]`。 按下按钮`i`改变其自身的价值`-1`，而其他每个值都会发生变化`+1`。 我们需要确定每个按钮应按下多少次。 输出是一个数组`c`， 在哪里`c[i]`是按下按钮的次数`i`， 或者`-1`如果不存在有效序列。 

最关键的困难在于，按一下会影响每个按钮，因此按钮不是独立的。 直接模拟可能必须执行数十亿次操作。 自从`n`与`200000`，甚至是一个花费`O(n)`每台印刷机的工作速度太慢。 我们需要用代数方式描述所有压力机并在线性时间内处理整个数组。 

粗心的解决方案可能会错过几种边缘情况。 第一个是`n = 1`。 例如，```
1
3
1
```唯一的按钮每当按下时就会减小，所以正确答案是`2`。 除以的公式`n - 2`仅当推导不小心时才必须单独处理这种情况，因为分母是`-1`，不为零。 

第二个特殊情况是`n = 2`。 例如，```
2
0 0
1 -1
```答案是```
0 1
```因为按下第二个按钮会改变状态`(0, 0)`到`(1, -1)`。 对于两个按钮，所有显示值的总和永远不会改变，因此无法从总和方程中恢复按下的总数。 盲目除以的解决方案`n - 2`在这里失败了。 

第三种边缘情况是，数学确定的按压次数可以是小数或负数。 例如，```
3
0 0 0
1 0 0
```无法解决。 使用整数除法的粗心实现可能会默默地截断非整数值并产生无效答案。 我们必须明确验证每个的完整性和非负性`c[i]`。 

最后，答案可能非常大。 的价值观`a[i]`和`b[i]`允许的幅度高达`10^9`，所以按下的次数也可以比`n`。 Python 整数可以自然地处理这个问题，而固定宽度的实现必须使用足够宽的整数类型。 

## 方法

 一种简单的方法是模拟压力机。 我们可以重复选择一个当前值还不正确的按钮，按下它，然后更新所有`n`显示值。 如果根据有效的解决方案做出选择，这样的模拟就是正确的，因为它准确地再现了语句中的操作。 问题在于操作次数。 即使只有三个按钮，按下的总数也可能达到数十亿次，并且每次按下都会更改所有三个值。 和`n = 3`例如，初始值的总和可能与目标总和相差数十亿，给出了相同顺序所需的按压总数。 因此，直接模拟可能需要`Θ(nS)`操作，其中`S`是按下的总数。 

蛮力之所以有效，是因为每个单独的按下都有一个简单的确定性效应，但它会失败，因为我们实际上不需要知道按下的顺序。 最终状态仅取决于每个按钮被按下的次数。 

让`S`是按下的总数，所以`S = c[1] + c[2] + ... + c[n]`。 

考虑一个特定的按钮`i`。 被按下`c[i]`次，以及其他每一次`S - c[i]`压力对其产生积极影响。 因此它的最终值为`b[i] = a[i] - c[i] + (S - c[i])`。 

重新整理后，`b[i] = a[i] + S - 2c[i]`，

所以`c[i] = (a[i] + S - b[i]) / 2`。 

这是关键的减少。 一旦我们知道了单一值`S`，每个单独的按压次数都是确定的。 

我们可以得到`S`通过对所有按钮的方程求和。 左边变成`sum(b)`，而右侧则变为`sum(a) + nS - 2S = sum(a) + (n - 2)S`。 

为了`n != 2`，这给出了`S = (sum(b) - sum(a)) / (n - 2)`。 

然后我们计算每个`c[i]`并检查它是否是一个非负整数。 

什么时候`n = 2`，系数`S`消失。 唯一不变的是`sum(b) = sum(a)`。 

如果这个条件不成立，目标就不可能实现。 如果成立，则令`d = b[0] - a[0]`。 

我们需要`c[1] - c[0] = d`。 我们总是可以选择最小的非负解：如果`d >= 0`， 拿`c[0] = 0`和`c[1] = d`; 否则采取`c[0] = -d`和`c[1] = 0`。 

案例`n = 1`也包含在一般公式中，因为`n - 2 = -1`。 它给出了`S = a[0] - b[0]`，这正是必须按下唯一按钮的次数。 仅当该值为负数时我们才需要拒绝它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(nS)`|`O(n)`| 太慢了 |
 | 最佳|`O(n)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 阅读`n`，初始数组`a`，以及目标数组`b`。 我们只需要它们的总和和个体差异，因此存储两个数组对于线性时间解决方案来说就足够了。 
2.如果`n = 2`,首先比较`sum(a)`和`sum(b)`。 每按一次都会改变一个值`-1`另一个由`+1`，所以总和是不变的。 如果总和不同，则输出`-1`。 
3.为了`n = 2`等和，计算`d = b[0] - a[0]`。 如果`d >= 0`， 输出`(0, d)`。 否则输出`(-d, 0)`。 无论哪种情况，两次按下次数之间的差异正是所需要的。 
4. 对于`n != 2`, 计算`S = (sum(b) - sum(a)) / (n - 2)`。 

使用前请确认划分是否准确。 如果分子不能被整除`n - 2`，不能存在整数的总压力。 
5. 对于每一个`i`， 计算`c[i] = (a[i] + S - b[i]) / 2`。 

分子必须是偶数，因为`c[i]`必须是整数。 还要求`c[i] >= 0`，因为按钮不能被按下负数。 
6.输出全部`c[i]`如果每项检查都成功。 价值`S`是从方程求和得出的，并且每个`c[i]`从按钮的精确方程导出`i`，因此这些计数再现了目标状态。 

### 为什么它有效

 让`S`是按下的总数。 对于每个按钮`i`， 确切地`c[i]`这些压力机中的一个会减少它，而其他的`S - c[i]`按压会增加它。 因此每个有效的解决方案必须满足`b[i] = a[i] + S - 2c[i]`。 为了`n != 2`，对这些方程求和唯一地确定`S`，因此算法检查唯一可能的按下总数，然后唯一地确定每个`c[i]`。 为了`n = 2`，求和方程不包含有关的信息`S`，但唯一的不变量是两个总和相等，并且构造的计数对实现了所需的差异。 因此，每个接受的输出都满足所有目标方程，而每个被拒绝的情况都违反了必要条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    sum_a = sum(a)
    sum_b = sum(b)

    if n == 2:
        if sum_a != sum_b:
            print(-1)
            return

        d = b[0] - a[0]

        if d >= 0:
            print(0, d)
        else:
            print(-d, 0)
        return

    numerator = sum_b - sum_a
    denominator = n - 2

    if numerator % denominator != 0:
        print(-1)
        return

    total = numerator // denominator

    if total < 0:
        print(-1)
        return

    ans = []

    for x, y in zip(a, b):
        value = x + total - y

        if value % 2 != 0:
            print(-1)
            return

        c = value // 2

        if c < 0:
            print(-1)
            return

        ans.append(c)

    print(*ans)

if __name__ == "__main__":
    solve()
```第一部分计算初始数组和目标数组的总和。 这些总和足以确定按下的总数`n != 2`。 

这`n == 2`分支出现在通式之前，因为它的分母为零。 对于两个按钮来说，只有按动次数的不同才是重要的。 如果第一目标值大了`d`，第二个按钮必须已被按下`d`比第一次更多次。 选择一个计数为零给出了有效的最小解。 

为了`n != 2`,`numerator`是`sum_b - sum_a`和`denominator`是`n - 2`。 蟒蛇的`%`运算符让我们在使用之前测试除法是否准确`//`。 此检查是必要的，因为截断按下的小数总数会产生无意义的计数。 

表达式`x + total - y`正是`2c[i]`。 在除法之前检查其奇偶校验可以防止奇数被默默地截断。 非负性检查强制执行按次数的物理意义。 

Python整数具有任意精度，因此即使中间和远大于`10^9`。

 ## 边缘情况

 ### 一键

 对于```
1
3
1
```我们有`sum(a) = 3`和`sum(b) = 1`。 自从`n - 2 = -1`,`S = (1 - 3) / (-1) = 2`。 

唯一的计数是`c[0] = (3 + 2 - 1) / 2 = 2`。 

算法输出`2`，这是完全正确的，因为每按一次都会减少唯一显示的值。 

### 两个按钮

 对于```
2
0 0
1 -1
```总和都为零，因此目标不会被不变量排除。 我们有`d = 1 - 0 = 1`。 

算法选择`c = (0, 1)`。 按第二个按钮后，第一个值增加到`1`第二个减少到`-1`。 目标达到了。 

如果输入是```
2
0 0
1 1
```初始总和是`0`而目标总和是`2`。 由于每次按下都会保留两个按钮的总和，因此算法会立即输出`-1`。 

### 按次数的分数

 考虑```
3
0 0 0
1 0 0
```总差为`1`， 和`n - 2 = 1`，所以这里`S = 1`，这实际上是积分。 但第一个单独计数将是`c[0] = (0 + 1 - 1) / 2 = 0`,

 而另外两个计数是`1/2`。 该算法到达单独奇偶校验并拒绝配置。 

这说明了为什么确定一个整数`S`还不够。 每一个`a[i] + S - b[i]`也必须是均匀的。 

### 负面新闻计数

 对于```
3
0 0 0
-2 1 1
```我们有`sum(a) = 0`,`sum(b) = 0`， 所以`S = 0`。 第一个按钮需要`c[0] = (0 + 0 - (-2)) / 2 = 1`,

 而另外两个则需要`c[1] = -1`和`c[2] = -1`。 

这些值不能代表按钮按下情况。 一旦遇到负计数，算法就会拒绝。 

### 大值

 对于```
3
1000000000 1000000000 1000000000
-1000000000 -1000000000 -1000000000
```总差是`-6000000000`， 和`n - 2 = 1`， 所以`S = -6000000000`。 由于按下的总数不能为负，因此算法会立即拒绝。 

该示例说明了代数解的另一个有用属性：它可以直接处理较大的量级，而无需执行模拟所需的大量单独操作。
