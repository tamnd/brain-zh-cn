 ## 解决方案
 ## 问题理解

 我们在以固定顺序处理操作时维护非负整数的多重集。 加法操作插入一个值，而删除操作则删除当前存在的一个值。 允许重复值，因此删除一份副本不得删除所有副本，除非只有一份副本。 

每次操作后，我们需要所有当前存储值的算术平均值。 如果多重集变空，则所需的答案为零。 

The direct mathematical definition is

 [
 \text{平均值}=\frac{\text{所有元素之和}}{\text{元素数量}}。 
]

 关键难点在于最多可以有20万次操作。 在两秒的限制下，每次操作后扫描整个多重集的算法将执行 (n^2) 次工作。 对于（n=200000），可以达到约400亿次元素访问，这远远超出了实际情况。 我们需要每个操作只需要常数或对数工作。 

值 (x) 可以大到 (10^9)，并且可以同时有 200,000 个元素。 它们的总和可以达到 (2\cdot10^{14})。 Python 整数可以精确处理这个范围，甚至双精度浮点数也可以表示 (2^{53}) 以内的每个整数，该整数大于 (2\cdot10^{14})。 对于所需的相对或绝对误差 (10^{-9})，最终除法也是安全的。 

The first edge case is an empty multiset. 例如，```
1
+ 0
```产生```
0.0
```因为唯一的元素为零。 更一般地，在添加然后删除唯一的元素之后，```
2
+ 5
- 5
```答案是```
5.0
0.0
```总是除以当前大小而不检查零的粗心实现会在第二次操作后尝试除以零。 

第二个边缘情况是包含重复值的多重集。 考虑```
3
+ 2
+ 2
- 2
```正确的输出是```
2.0
2.0
2.0
```删除操作仅删除一次出现的情况，因此 1`2`遗迹。 将结构视为普通集的实现可能会完全删除该值并错误地报告零。 

第三个边缘情况是一个很大的值。 例如，```
2
+ 1000000000
+ 1000000000
```有答案```
1000000000.0
1000000000.0
```使用不必要的窄整数类型的解决方案可能会在计算总和时溢出。 Python 的任意精度整数避免了这个问题。 

## 方法

 蛮力方法实际上遵循算术平均值的定义。 保留当前元素，执行请求的插入或删除，然后迭代每个剩余元素以计算其总和并除以元素数。 这是正确的，因为它会在每次操作后准确地重建请求的数量。 

问题是重复扫描。 如果多重集大约包含 (n/2) 个元素（对于大多数 (n) 次操作），则总工作量是二次方。 在最坏的情况下，访问的元素数量约为

 [
 1+2+\dots+(n-1)=\frac{n(n-1)}2.
 ]

 对于 (n=200000)，即使在这种简单的规模不断增加的情况下，访问量也约为 200 亿次。 始终保持多重集较大的构造仍然可以产生相同的二次阶。 这样的解决方案无法满足时间限制。 

解锁更快解决方案的观察结果是，插入或删除仅改变一个位置的总和和元素总数。 我们不需要检查其他元素，因为它们对这两个数量的贡献保持不变。 

假设当前总和为 (S)，当前大小为 (C)。 添加 (x) 将它们更改为 (S+x) 和 (C+1)。 删除一次 (x) 将其更改为 (S-x) 和 (C-1)。 然后可以立即将答案计算为 (S/C)。 

对于这个问题实际上没有必要存储整个多重集。 该语句保证每次删除都是有效的，因此我们不需要数据结构来验证(x)是否存在。 我们只需要总和和元素数量。 重复值也不需要特殊处理，因为每次出现都会独立地影响总和和计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | ---|
 | 蛮力 | (O(n^2)) | (O(n)) | (O(n)) | 太慢了 |
 | 最佳| (O(n)) | (O(n)) | (O(1)) 辅助空间 | 已接受 |

 ## 算法演练

 1. 初始化`total = 0`和`count = 0`。 这些变量表示所有当前发生的事件及其总数的总和。 
2.读取下一个操作及其值`x`。 如果操作是`+`， 添加`x`到`total`并增加`count`一个。 这准确地反映了插入一个新的事件。 
3. 如果操作是`-`, 减去`x`从`total`并减少`count`一个。 输入保证可以删除这种情况，因此不需要成员资格检查或频率图。 
4. 应用操作后，检查`count`。 如果为零，则输出`0.0`，因为空多重集的算术平均值定义为零。 否则，输出`total / count`。 
5. 对所有 (n) 个操作重复此过程。 每个运算仅使用恒定数量的算术运算，因此完整的处理是线性的。 

### 为什么它有效

 不变的是，在每次处理操作之后，`total`等于多重集中当前出现的每个事件的总和，而`count`等于这些事件出现的次数。 最初，对于空多重集，这两个值都是正确的。 插入恰好将 (x) 添加到总和中，并将一次出现添加到计数中。 删除操作会从总和中删除 (x)，并从计数中删除一次。 因此，每次操作后，不变式仍然成立。 当多重集非空时，`total / count`正是它的算术平均值，并且当`count`为零，算法输出单独定义的值零。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    total = 0
    count = 0
    output = []

    for _ in range(n):
        op, x = input().split()
        x = int(x)

        if op == '+':
            total += x
            count += 1
        else:
            total -= x
            count -= 1

        if count == 0:
            output.append("0.0")
        else:
            output.append(str(total / count))

    sys.stdout.write("\n".join(output))

if __name__ == "__main__":
    solve()
```这两个状态变量直接实现演练中的不变量。`total`在计算答案之前更新，因为请求的平均值是针对当前操作之后的多重集，而不是之前的。 

删除分支使用`total -= x`和`count -= 1`。 没有频率字典，因为输入明确保证删除始终引用现有的出现。 维持不必要的频率会增加内存使用量，但对答案没有贡献。 

这`count == 0`检查必须在划分之前进行。 该问题明确将空多重集的均值定义为零，因此这种情况不能通过普通除法来处理。 

Python 的整数运算保持`total`即使达到 (2\cdot10^{14}) 也是精确的。 除法产生一个浮点值。 其相对精度完全在可能答案范围所需的 (10^{-9}) 容差范围内。 

答案收集于`output`并且编写一次可以避免对每一行执行单独的系统级输出操作。 当有 200,000 个答案时，这很有用。

 ## 边缘情况

 空多重集是显式处理的。 对于输入```
2
+ 5
- 5
```第一个操作给出`total = 5`和`count = 1`，所以答案是`5.0`。 第二个操作将状态更改为`total = 0`和`count = 0`。 跳过除法，算法输出`0.0`，匹配空多重集的特殊定义。 

重复值会自动表示，因为`count`计算出现次数而不是不同的数字。 为了```
3
+ 2
+ 2
- 2
```各州是`(2, 1)`,`(4, 2)`， 和`(2, 1)`为了`(total, count)`。 每个答案都是`2.0`。 无需区分哪个物理事件被删除，因为相同的值具有相同的贡献。 

零值不需要特殊的算术处理。 为了```
2
+ 5
+ 0
```状态从`(5, 1)`到`(5, 2)`，生产`5.0`和`2.5`。 零会增加元素数量而不改变总和，正如聚合表示所预测的那样。 

Python 中的最大值也不会导致溢出。 和```
2
+ 1000000000
+ 1000000000
```总数变为`2000000000`，计数变为`2`, 给予`1000000000.0`。 经过 200,000 次此类插入，总数可以达到`200000000000000`，Python 准确表示。 

最大运算次数并不需要更大的算法结构。 添加 200,000 次后，每次操作仍包含一次更新`total`, 一项更新为`count`，和一个部门。 总工作量线性增长，这是使解决方案适合输入限制的属性。
