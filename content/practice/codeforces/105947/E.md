 ## 解决方案
 ## 问题理解

 我们给出了几个测试用例，每个测试用例都包含一个整数数组。 对于每个数组，任务是计算有多少个连续子数组恰好包含`k`独特的价值观。 

连续子数组是通过选择左边界和右边界而不对元素重新排序而形成的数组的切片。 “恰好k个不同的值”意味着如果我们查看该切片内的所有元素，其中出现的唯一数字的数量恰好是`k`。 

因此，每个测试用例的输出都是一个数字：此类子数组的总数。 

这些约束意味着经典的子数组计数设置。 所有测试用例的总长度约为`2 · 10^5`，这排除了每个测试用例都是二次的任何解决方案。 在最坏的情况下，对所有子数组进行简单的 O(n²) 枚举将执行大约 2e10 次操作，这远远超出了限制。 这推动我们采用线性或近线性技术，通常是滑动窗口或两个指针。 

有一些微妙的边缘情况经常会破坏不正确的解决方案。 

如果所有元素都相等且`k = 1`，每个子数组都是有效的。 例如，`[5, 5, 5]`应该产生 6 个有效的子数组。 错误地只计算最大段的简单解决方案会导致计数不足。 

如果`k`大于整个数组中不同元素的数量，则答案必须为零。 例如，`[1, 2, 1]`和`k = 3`没有有效的子数组，即使每个子数组最多有 2 个不同的值。 

另一个棘手的情况是重复项交错时。 例如，`[1, 2, 1, 2]`和`k = 2`有许多有效的子数组，计数需要仔细处理边界； 简单地跟踪不同的计数而不进行适当的缩小会导致重叠窗口的计数过多。 

## 方法

 蛮力的想法很简单。 我们迭代每个左端点，扩展右端点，并维护一组元素来计算不同值。 每次扩展右指针时，我们都会重新计算或更新集合并检查不同值的数量是否正好`k`。 这可以正确计算所有有效子数组，因为它直接检查每个可能的段。 

问题是性能。 每次扩展维护一个集合需要 O(1) 摊销，但在最坏的情况下，我们仍然检查每个测试用例的 O(n²) 个子数组。 当总输入大小为 2e5 时，这是不可行的。 

关键的观察是我们实际上并不需要直接计算“恰好 k”。 相反，计算“至多 k”个不同值要容易得多。 标准的滑动窗口技术允许我们维护一个窗口`[l, r]`使得它总是最多包含`k`独特的元素。 对于每个`r`，所有以`r`并从任何地方开始`l`到`r`在此约束下有效，贡献`(r - l + 1)`子数组。 

一旦我们可以计算`atMost(k)`，我们可以将问题转化为两个更简单问题的差异：子数组与`k`不同的值等于`atMost(k) - atMost(k - 1)`。 这是有效的，因为每个子数组都恰好`k`不同的值包含在`atMost(k)`但被排除在外`atMost(k - 1)`。 

这将问题转化为两个线性滑动窗口传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 滑动窗口（最多 k + 减法）| 每次测试 O(n) | O(n) | 已接受 |

 ## 算法演练

 我们构建一个辅助函数`at_most(k)`最多计算子数组`k`独特的价值观。 

1.初始化两个指针`l = 0`和`result = 0`。 还维护频率图`freq`和一个变量`distinct = 0`。 地图跟踪每个值在当前窗口中出现的次数。 
2. 展开右侧指针`r`从`0`到`n - 1`，添加`a[r]`到窗户。 如果该值以前不存在，则增加`distinct`。 更新其在地图中的频率。 
3.如果`distinct`超过`k`，从左侧缩小窗口。 移动`l`向前同时递减频率。 当频率变为零时，减小`distinct`。 这恢复了窗口最多具有的不变量`k`独特的价值观。 
4. 窗口有效后，所有以`r`并开始之间`l`和`r`是有效的。 添加`(r - l + 1)`到`result`。 这是有效的，因为每个这样的子数组仍然位于当前有效窗口内。 
5. 返回`result`。 

对于最终答案，计算`at_most(k) - at_most(k - 1)`。 

### 为什么它有效

 每走一步，窗户`[l, r]`是最小的左边界，使得子数组结束于`r`最多包含`k`独特的价值观。 任何较小的左边界都会违反约束，任何较大的左边界都会错过有效的子数组。 这使得贡献计数准确，因为每个子数组都以`r`在处理其右端点时仅计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def at_most(a, k):
    if k < 0:
        return 0
    freq = defaultdict(int)
    l = 0
    distinct = 0
    res = 0

    for r, x in enumerate(a):
        if freq[x] == 0:
            distinct += 1
        freq[x] += 1

        while distinct > k:
            y = a[l]
            freq[y] -= 1
            if freq[y] == 0:
                distinct -= 1
            l += 1

        res += r - l + 1

    return res

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    print(at_most(a, k) - at_most(a, k - 1))
```核心结构是两指针滑动窗口。 频率字典跟踪当前窗口内的出现情况，并且`distinct`避免从头开始重新计算唯一元素的数量。 

一个常见的错误是为每个重新计算一个集合`r`，这会默默地将解变成二次方。 另一个是忘记了收缩必须持续到再次满足约束为止； 单一的有条件收缩是不够的。 

最后的减法是必不可少的。 没有`at_most(k - 1)`，该函数将计算所有少于的子数组`k`也有不同的价值观。

import sys, io
from collections import defaultdict

def solve():
    input = sys.stdin.readline
    def at_most(a, k):
        if k < 0:
            return 0
        freq = defaultdict(int)
        l = 0
        distinct = 0
        res = 0
        for r, x in enumerate(a):
            if freq[x] == 0:
                distinct += 1
            freq[x] += 1
            while distinct > k:
                y = a[l]
                freq[y] -= 1
                if freq[y] == 0:
                    distinct -= 1
                l += 1
            res += r - l + 1
        return res

        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        out.append(str(at_most(a, k) - at_most(a, k - 1)))
    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

 ## 边缘情况

 当所有元素都相同且`k = 1`，窗口永远不会缩小，因为`distinct`保持为 1。该算法对每个位置结束的每个前缀进行计数，这自然会产生子数组的完整三角形数。 为了`[5, 5, 5]`，贡献为 1、2 和 3，总和为 6，匹配正确的计数。 

什么时候`k = 0`, 帮手`at_most(k - 1)`变成`at_most(-1)`它被定义为零，因此结果也为零。 这避免了特殊的大小写无效配置，其中子数组不能具有零个不同值。 

当所有元素都不同且`k = 2`，窗口急剧缩小。 为了`[1,2,3,4]`，每个位置的有效贡献为 1、2、2 和 2，即 7`at_most(2)`，并减去`at_most(1)`删除单元素子数组，只留下具有两个不同值的子数组。
