 ## 解决方案

 ## 问题理解

 我们给定了前 n 个正整数，我们必须将它们分成两个非空组。 每个整数必须恰好属于一组，并且我们希望两组的总和尽可能接近。 

如果我们从结构的角度思考，这就是将固定集合 {1, 2, ..., n} 划分为两个子集。 对目标而言唯一重要的量是子集总和之间的差异。 由于总和是固定的，最小化差异相当于使一个子集的和尽可能接近总和的一半。 

前 n 个整数的总和为 n(n+1)/2，因此目标是构造一个总和接近 S/2 的子集。 

约束 n ≤ 60000 足够大，任何指数子集构造都是不可能的。 暴力子集枚举将涉及 2^n 种可能性，这远远超出了可行的限制。 即使任何试图通过回溯或 DP 独立地决定包含状态达到 S 的方法也太大了，因为当 n = 60000 时，S 的数量级为 1.8 × 10^9。 

该约束的关键含义是我们无法直接推理所有子集，并且我们必须利用序列 1, 2, ..., n 中的结构。 

当 n 非常小时，会出现微妙的边缘情况。 对于 n = 2，唯一有效的划分是 {1} 和 {2}，产生差 1。对于 n = 3，接近平衡的分割存在为 {1, 2} 和​​ {3}，产生和 3 和 3，因此差 0。任何解决方案都必须正确处理总和的奇偶校验情况，因为有时可以实现完美平衡，有时则不能。 

另一种失败模式是在没有结构的情况下尝试从 1 向上或从 n 向下进行贪婪选择。 例如，始终将较大的数字放在前面可能会过早超出并且无法恢复平衡，因为剩余的数字太小而无法补偿。 

## 方法

 暴力尝试会尝试将 1 到 n 中的每个数字分配到两组中的一组并跟踪最佳差异。 这会检查 2^n 个分区，即使每次检查的时间复杂度为 O(n)，总工作量也会增长为 n·2^n，这在 n = 40 时就变得不可能了。 

更结构化的动态规划方法可能会尝试计算所有可实现的子集总和，最高可达 S/2。 然而，S 本身随 n 呈二次方增长，因此即使是基于位集的 DP 在最坏的情况下也需要大约 1.8 × 10^9 位，这在内存和时间上都是不可行的。 

关键的观察结果是数字是连续的。 这意味着我们可以从最大数向下贪婪地构造一个最优分区。 每个大数字支配所有较小的剩余数字组合或至少强烈影响平衡决策。 我们可以直接构建一个总和接近 S/2 的子集，而不是解决组合子集和问题，方法是始终采用最大的可用元素（如果它不会使我们超出目标太远）。 

该策略变成了向总金额一半的受控贪婪积累。 由于我们始终考虑剩余总和并选择最大的可行元素，因此我们永远不会失去精确达到目标的能力，因为较小的数字始终可用于微调最终总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | DP 超过总和 | O(nS) 或 O(S) 空间 | O(S)| 太大|
 | 贪婪构造| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将总和表示为 S，将目标表示为 T = S // 2。我们希望构造一个子集 A，其总和尽可能接近 T。

1. 计算 S = n(n+1)/2 并设置 T = S // 2. 这定义了两组之间的理想平衡点。 
2. 初始化一个空集合 A 并设置 current_sum = 0。该集合将代表我们正在构造的第一个组。 
3. 将 i 从 n 迭代到 1。在每一步，考虑将 i 添加到 A 是否使我们保持在或接近 T。 
4. 如果 current_sum + i ≤ T，则将 i 包含在 A 中并更新 current_sum。 原因是，应采用任何不超过目标的数字，因为较大的值比较小的值更会降低灵活性。 
5. 否则，跳过 i 并将其隐式分配给第二组。 跳过使 i 在补集组中可用，这确保我们仍然可以形成完整分区。 
6.处理完所有数字后，输出绝对差|S - 2·current_sum| 和集合A。 

该结构使用可用物品 {1, ..., n} 按降序有效地将背包填充至容量 T。 

它起作用的原因来自于连续整数的简单显性属性。 在任何步骤中，剩余未使用的数字恰好是整数的连续前缀，并且贪心选择确保我们永远不会错过可行的最佳总和：如果一个数字适合，则采用它不会阻止实现更接近 T 的近似值，因为使用剩余整数仍然可以进行所有较小的调整。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
S = n * (n + 1) // 2
T = S // 2

chosen = []
current = 0

for i in range(n, 0, -1):
    if current + i <= T:
        chosen.append(i)
        current += i

group2 = set(chosen)

print(abs(S - 2 * current))
print(len(chosen), *chosen)
```该解决方案首先计算总和和目标一半。 贪心循环处理从 n 到 1 的数字，保持以下不变式：`current`是所选元素的总和，并且永远不会超过 T。每个元素都会根据剩余容量进行测试，并且仅在适合时才包含在内。 

使用第二组和为 S - 当前的恒等式来计算输出差值，因此绝对差值变为 |current - (S - current)| = |S - 2·当前|。 

一个微妙的点是我们从未明确构建第二组。 它隐式地是所选集合的补充，这保证了有效性并避免了额外的工作。

 ## 边缘情况

 对于 n = 2，算法从 T = 3 // 2 = 1 开始。它首先处理 2，跳过它，然后取 1。结果组是 {1} 和 {2}，给出差值 1，这是最佳的，因为完美平衡是不可能的。 

For n = 3, S = 6 and T = 3. The algorithm considers 3 first and takes it, then skips 2 and 1 since both would exceed capacity. 这会产生 {3} 和 {1, 2}，两者之和均为 3，因此差值为 0。贪婪选择成功，因为目标与大元素完全对齐。 

For n = 4, S = 10 and T = 5. The algorithm takes 4, then takes 1, reaching exactly 5. The remaining elements form the second group. This shows how smaller elements compensate for earlier large choices, preserving reachability of the exact target.
