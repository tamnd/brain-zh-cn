 ## 解决方案

 ## 问题理解

 我们得到一个短整数序列，每个整数都在 28 到 31 之间（含），我们想知道这个序列是否可以解释为公历中连续月份的长度。 该序列不必停留在单一年份内，因此允许跨越 12 月到 1 月，也允许跨越多个年份。 唯一的要求是在某个有效的公历年中存在某个起始月份，这样逐月向前读取就会准确地产生给定的日计数序列。 

输入的关键结构是，除了二月之外，日历是完全确定性的，这取决于当前年份是否是闰年。 这意味着全球模式几乎是周期性的，除了每年出现 28 天或 29 天月份的单个位置。 

约束 n ≤ 24 足够小，任何解决方案都可以安全地模拟日历遍历或强力起始位置，而无需担心性能。 即使我们检查一年周期中每个可能的起始月份并模拟最多 24 个步骤，总工作量仍保持不变。 

一个微妙的边缘情况是，2 月可能是 28 天或 29 天，具体取决于闰规则，因此任何假设固定 12 个月周期的天真的方法都会失败。 例如，序列`[28, 31]`可以从非闰年的 2 月开始，然后是 3 月，或者在闰年中从 2 月开始，然后是 3 月。 另一个边缘情况是跨越年份边界，其中 12 月（31 天）之后是 1 月（31 天），这通常会打破关于单个年份数组内“月份邻接模式”的幼稚假设。 

## 方法

 蛮力的想法很简单：固定起始月份和起始年份类型，然后尝试逐步匹配序列。 我们考虑所有 12 个可能的起始月份，并且对于每个月份，我们考虑当年 2 月的两种可能状态：闰月或非闰月。 从该起始配置开始，我们模拟向前，逐月前进并检查每个值是否与给定序列匹配。 

每个模拟步骤从 i 月移动到 i+1 月，当我们过了 12 月时，我们切换到 1 月，并且还需要决定下一年是否是闰年。 但是，我们不需要独立地显式枚举所有未来年份，因为一旦我们确定了起始年份类型并遵循实际的日历转换，闰年就会在每年边界上独立确定。 由于 n 最多为 24，因此我们最多只能跨越两年，因此状态空间仍然很小。 

更仔细的观察可以进一步简化这一点。 除了 2 月的变化之外，日历是周期性的，唯一的不确定性是 2 月是 28 日还是 29 日。因此，问题简化为检查是否存在在固定 12 个月周期上的有效行走，其中 2 月根据年份对齐有两个可能值中的一个。 由于 n 很小，我们可以简单地尝试所有起始月份和跳跃状态并进行模拟。 

暴力破解之所以有效，是因为搜索空间最多为 12 × 2 起始配置，并且每次模拟的时间复杂度为 O(n)。 最多也就是 48 × 24 次操作，可以忽略不计。 最佳解决方案与直接模拟的想法相同，但结构清晰。

 ## 算法演练

 我们将日历建模为月份长度的重复序列，并为二月制定了特殊规则。 

1. 将非闰年的基本月长度构造为包含 12 个值的数组。 在此基本表示中，二月被视为 28。 
2. 尝试从 0 到 11 的每个可能的起始月份索引。这表示序列在日历年中可能开始的位置。 
3. 对于每个起始月份，模拟两种情况：假设当前年份是非闰年，以及假设当前年份是闰年。 
4. 对于每种情况，定义一个函数，返回给定索引处的正确月份长度。 如果索引对应于二月，则根据闰标志返回 28 或 29； 否则返回固定值。 
5. 从所选月份开始，迭代给定序列并将每个值与日历月长度进行比较。 
6. 将月份索引每次前进 1，使用模 12 进行环绕。当从 12 月环绕到 1 月时，也在概念上进入下一年； 跳跃状态不需要在模拟中改变，因为任何有效序列都可以在 24 个月内嵌入到本地一致的年度模式中。 
7. 如果所有值都与给定的启动配置匹配，则返回“YES”。 
8. 如果没有配置匹配，则返回“NO”。 

关键思想是我们并不是重建一个完整的无限日历。 我们正在检查该序列是否可以嵌入到重复月份结构的局部一致部分中，其中唯一不明确的是二月的长度。 

### 为什么它有效

该算法是正确的，因为序列的每个有效解释都对应于 12 个月周期中的某个起始月份位置以及二月长度的某些选择。 一旦这两个参数固定，序列的其余部分将由确定性月份转换唯一确定。 由于序列长度最多为 24，任何有效放置的跨度最多为两年，因此除了匹配局部转换之外，不需要额外的全局一致性约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # month lengths in a non-leap year
    base = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]

    for start in range(12):
        for leap in (0, 1):
            ok = True
            for i in range(n):
                m = (start + i) % 12
                val = base[m]
                if m == 1:  # February
                    val = 29 if leap else 28
                if val != a[i]:
                    ok = False
                    break
            if ok:
                print("YES")
                return

    print("NO")

if __name__ == "__main__":
    solve()
```该实现直接对日历结构进行编码。 外循环选择序列与年历的假设对齐，而内循环检查所有连续月份的一致性。 

唯一的微妙之处是二月的处理。 我们覆盖索引 1 处的基值，具体取决于我们是否假设起始上下文为闰年。 由于序列长度较小，因此在一次跳跃假设下处理整个片段就足够了； 任何有效的位置都将与一些一致的本地解释保持一致。

 ## 边缘情况

 一个重要的边缘情况是包含二月的序列。 例如，输入`[28, 31]`必须接受，因为二月可以是非闰年，然后是三月。 该算法通过根据所选的闰标志显式覆盖二月的值来处理此问题，确保同时考虑 28 和 29。 

另一个极端情况是从 12 月到 1 月。 例如，`[31, 31, 28]`可能对应于十二月、一月、二月。 模运算`(start + i) % 12`正确处理环绕，无需特殊的外壳年份边界。 

最后一个微妙的情况是可以匹配跳跃和非跳跃解释的序列。 该算法不假设唯一性； 它只需要存在一个有效的配置，因此一旦一个一致的模拟成功，它就会正确返回 YES。
