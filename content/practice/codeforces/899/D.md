 ## 解决方案

 ## 问题理解

 我们有一家商店，其中包含价格从 1 到 n 的商品，其中第 i 件商品的价格恰好为 i。 我们必须选择一对无序的不同物品，计算它们的总价格，并查看该总和的小数表示形式。 重要的是有多少个尾随数字等于 9。 

在所有可能的对中，我们首先要最大化总和中尾随 9 的数量。 在找到最佳质量后，我们会计算有多少对达到了该质量。 

一个关键的观察是值 n 可以大到 10^9，因此我们无法迭代所有对。 大约有 n^2 / 2 对，这远远超出了任何可行的计算。 任何有效的解决方案都必须将搜索空间减少到仅取决于 n 的位数（最多 10）。 

一种简单的方法是枚举所有对 (i, j)，计算 i + j，计算尾随 9，并跟踪最大值。 即使对于 n = 10^5，这也会立即失败，因为它需要大约 10^10 次操作。 

如果我们尝试仅推理最后一位数字，则会出现另一个微妙的问题。 例如，以 9 结尾的对的总和仅取决于 i + j mod 10，但最大化多个尾随 9 取决于所有数字位置的进位。 任何独立处理数字而不处理进位的方法都会在像 49 + 50 = 99 这样的情况下失败，其中进位链创建的 9 后缀比本地推理建议的更长。 

核心困难在于尾随的 9 对应于以 10 为基数的 i + j 上的非常结构化的条件，并且我们必须计算满足最强此类条件的对。 

## 方法

 我们从暴力的角度开始。 如果我们明确地尝试所有对，我们计算 i + j 并检查有多少个尾随数字是 9。每对的成本是 O(log n) 来计算尾随 9，总体上是 O(n^2 log n)。 对于 n = 10^9 来说这已经是不可能的了。 

我们需要一种方法来完全避免迭代对。 关键的见解是重新构建总和的条件。 

一个数字以 k 个 9 结尾当且仅当它与 10^k − 1 模 10^k 全等。 因此，对于每个 k，我们需要 (i, j) 对，使得：

 i + j == 10^k − 1 (mod 10^k)

 对于固定的 k，这是一个模块化配对问题。 如果我们减少 [1, n] 中的所有数字 i 模 10^k，我们可以使用频率计数来计算有多少对总和为 10^k − 1 mod 10^k。 

然而，我们仍然需要确定至少存在一对有效的最大 k。 随着 k 的增加，模量也随之增加，约束也随之收紧。 最大可能的 k 以 2n 位数字为界，最多为 10。 

所以我们可以从 0 向上尝试 k，并为每个 k 计算存在多少个有效对。 具有非零计数的最大 k 就是我们关心的答案。 

一旦 k 确定，计数对就很简单了。 我们通过残差 mod 10^k 对数字进行存储，并将 x 与 (10^k − 1 − x) 匹配。 必须注意避免重复计算并确保 i < j。 

这将问题减少到对 n 个元素的线性扫描最多 10 次迭代，但我们仍然无法直接迭代所有 i 直到 n。 

第二个关键观察结果是残基以周期 10^k 周期性重复。 因此，我们可以通过将 [1, n] 拆分为大小为 10^k 的完整块加上余数块来计算频率。 这允许在 O(10^k) 中计算每个残基的频率，并且由于 k ≤ 10，因此这仍然是可管理的。

 | 残留物模块化计数 | O(10^k·k) | O(10^k·k) | O(10^k) | O(10^k) | 已接受 |

 ## 算法演练

 我们通过从小到大检查尾随 9 的可能长度并计算每个长度的有效对来解决该问题。

1. 固定候选 k，这意味着我们希望以 k 位数字结尾的和都等于 9。这意味着我们需要 i + j == 10^k − 1 (mod 10^k)。 我们将计算有多少对满足这个条件。 
2. 计算 m = 10^k。 我们想要以 m 为模，因此每个数字 i 都映射到 i mod m。 
3. 构建大小为 m 的频率数组 cnt，其中 cnt[r] 是 [1, n] 中模 m 为 r 的余数的整数个数。 这是通过观察长度为 m 的完整周期和剩余的部分块来计算的。 每个完整循环恰好贡献每个残基的一次出现。 
4. 一旦频率已知，我们就计算残基对 (r, s)，使得 r + s == m − 1 mod m。 我们通过迭代 r 并将其与 s = (m − 1 − r + m) % m 配对来实现此目的。 
5. 计数时，必须避免重复计数。 我们只将 r ≤ s 配对，并使用组合 cnt[r] 选择 2 单独处理 r = s 的情况。 
6. 计算给定 k 的有效对的数量后，我们检查它是否非零。 如果是，我们存储它并尝试 k + 1。 
7. 最终答案是与存在至少一对有效的最大 k 相对应的对计数。 

### 为什么它有效

 不变量是，对于每个固定 k，频率数组正确表示 [1, n] 中有多少个数字落入模 10^k 的每个残差类别。 每个有效对都被精确计数一次，因为每一对都映射到满足模约束的精确残基对，并且配对过程通过限制 r ≤ s 来强制唯一性。 由于增加 k 只会加强对总和的约束，因此找到的最大 k 恰好是尾随 9 的最大可能数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_pairs(n, k):
    m = 10 ** k
    cnt = [0] * m

    # count residues in [1, n]
    full = n // m
    rem = n % m

    for r in range(m):
        cnt[r] = full

    for i in range(1, rem + 1):
        cnt[i % m] += 1

    target = m - 1
    res = 0

    for r in range(m):
        s = (target - r) % m
        if r > s:
            continue
        if r == s:
            res += cnt[r] * (cnt[r] - 1) // 2
        else:
            res += cnt[r] * cnt[s]

    return res

def solve():
    n = int(input().strip())

    best_k = 0
    best_ans = 0

    for k in range(0, 10):
        if 10 ** k > 2 * n + 10:
            break
        val = count_pairs(n, k)
        if val > 0:
            best_k = k
            best_ans = val

    print(best_ans)

if __name__ == "__main__":
    solve()
```功能`count_pairs`是核心组件。 它使用大小为 m 的完整块和余数前缀来构造余数计数，而无需迭代所有数字。 这避免了对 n 超出 O(1) 算术的依赖。 

配对逻辑通过仅处理 r ≤ s 来小心地强制执行唯一性。 相等情况使用 nC2 来避免以两种方式将元素与其自身配对。 

k 上的外层循环是安全的，因为 k 受 2n 所需位数的限制，一旦 10^k 超出该范围，就不会存在新的有效对。

对于 k = 1、m = 10，我们计算数字 1 到 7 的余数 mod 10。有效条件是 sum == 9 mod 10。有效对是 (2,7)、(3,6)、(4,5)，给出 3 对。 

由于 k = 1 产生有效对而 k = 2 不产生有效对，因此答案为 3。

对于 k = 1，许多对的总和都是以 9 结尾的数字。

 ## 边缘情况

 最小输入（例如 n = 2）测试算法是否正确处理非常小的频率阵列并避免自配对。 唯一的一对是 (1, 2)，它的和是 3，不以 9 结尾，所以答案是 0。 

对于 n = 50，算法正确地识别出 k = 2 仅由于进位链才变得可行。 该对 (49, 50) 产生 99，而没有其他对达到两个尾随 9，并且模块化计数隔离了该单个有效组合。 

对于像 10^9 这样的较大 n，残差构造仍然有效，因为它仅依赖于算术分解为完整块和余数段，从而避免了整个范围内的任何迭代。
