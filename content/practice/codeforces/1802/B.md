 ## 解决方案
 ## 问题理解

 我们正在模拟一条时间线，随着时间的推移，新的豚鼠会到达，偶尔会发生“暴露”事件，所有当前拥有的动物突然都会暴露其性别。 困难在于，在揭晓之前，每只豚鼠都是完全模糊的，因此在最糟糕的任务中，任何两只动物都可能最终成为相同性别或不同性别。 

每只豚鼠必须被放入鸟舍中，每个鸟舍最多可容纳两只动物，但一个关键的限制是我们永远不允许在同一个鸟舍中出现混合性别的配对。 由于性别在揭晓之前是未知的，因此我们在那一刻之前创建的任何分组在两种可能的性别分配下都必须是安全的。 

这些操作是连续几天进行的。 在标记为 1 的那一天，一只新的豚鼠出现，必须立即分配到某个鸟舍。 在标记为 2 的那一天，所有现有动物的性别都会被揭示，这突然为我们提供了完整的信息，并使我们能够在考虑下一次到达之前进行最佳重组。 

输出是鸟舍的最小数量，保证我们始终能够保持有效的安排，无论性别如何，无论我们在每次展示之前如何分配动物。 

限制很大，每个测试用例最多 100000 次操作，所有测试总共 100000 次。 这立即排除了任何模拟所有可能的性别分配或维持每只动物的复杂状态的方法。 我们需要一个能够在恒定时间内处理每个事件的解决方案。 

没有任何 2 操作的长序列 1 操作会产生一个微妙的问题。 在这样的时间里，我们被迫盲目地分配动物。 另一个棘手的情况是，在插入突发之后立即发生 2 操作：此时，我们必须重新解释所有当前未分配动物的最坏情况结构。 

一种幼稚的方法可能会尝试显式跟踪可能的性别配置或贪婪地动态分配对。 这失败了，因为对手（未知的性别分配）有效地迫使我们在每个点都假设最差的划分。 

## 方法

 一种强力的解释是在每次揭示后模拟每一种可能的性别分配，并计算出鸟舍的最佳可能分组。 对于 k 只豚鼠，这意味着考虑所有 2^k 分配并检查可行性，这是指数级的，即使对于 30 左右的 k 来说也是不可行的。 

关键的观察是，在揭示之前，我们没有任何信息，因此每只豚鼠都表现得像一个无法区分的不确定项。 最坏情况的解释迫使我们假设，当揭秘发生时，性别会以敌对的方式排列，以最大限度地增加所需的鸟舍数量。 

在揭晓之前的任何时刻，假设我们有 k 只豚鼠。 揭露后，最糟糕的可能分裂是一种性别出现 ⌈k/2⌉ 次，另一种性别出现 ⌊k/2⌋ 次。 然而，更重要的结构限制是每个鸟舍最多只能容纳一对同性，并且任何剩余的单身人士都会被迫分开笼子。 

更深层次的简化来自于将每个鸟舍视为空的，包含一对已知的豚鼠，或包含一只不确定的豚鼠。 每次揭露发生时，我们都可以最佳地压缩系统：从 k 只动物中，我们能做的最好的事情就是将它们分成 ⌊k/2⌋ 对，并可能剩下一只。 剩余的结构决定了为将来的插入保留多少“可用插槽”。

正确的贪婪观点是，每次揭示后，我们都会重新组织成与最坏情况性别分裂一致的最小数量的鸟舍。 这会产生一个干净的状态：我们始终保持当前“未配对”豚鼠的数量，并且每次揭示都允许我们将尽可能多的豚鼠转换为稳定的配对。 

因此，解决方案简化为跟踪自上次显示以来存在多少动物，并在每次显示后将它们转换为压缩形式，其中只有一小部分残差集很重要。 每个新的插入要么消耗现有鸟舍中的一个空闲槽，要么在最坏情况的假设下强制创建一个新的槽。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力对待性别分配| O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 每次显示时进行贪婪压缩 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从左到右处理操作，同时维护一个表示当前“未解决”的豚鼠数量的单个值，这意味着自上次医生访问以来已添加了它们。 

1.初始化一个计数器`cur = 0`，代表自上次揭示以来的豚鼠数量，以及`ans = 0`，代表最差状态下所需的鸟舍。 
2. 迭代日程表中的每一天。 
3. 如果操作是`1`, 增量`cur`因为添加了新的豚鼠，并且必须立即置于不确定性之下。 这反映出它可能会增加最坏情况下的配对压力。 
4. 如果操作是`2`，我们处理一个揭示事件。 此时此刻，所有`cur`豚鼠可以最佳地重新安置在鸟舍中。 
5. 要计算最坏情况的要求，请注意：`cur`动物最多可以形成`cur // 2`安全的一对，可能还有一个剩下的单人。 这些动物所需的鸟舍数量恰好是`cur - (cur // 2)`，这简化为`(cur + 1) // 2`。 
6. 我们将这笔贡献累积到`ans`，因为这些鸟舍必须存在才能安全地容纳当前段。 
7. 重置`cur = 0`，因为在揭示之后，我们在概念上以最佳方式重新组织一切并重新开始。 

关键的微妙之处在于，我们从不合并由揭示分隔的不同部分的信息。 每个部分都独立运行，因为医生就诊可以解决所有不确定性并允许完全重新配置。 

### 为什么它有效

 不变的是，在任何两次揭示操作之间，该区间内的所有豚鼠都是无法区分的不确定元素，我们只需要在解析时考虑它们的最坏情况分组。 在揭示时，我们用最坏情况性别分配下所需的最少数量的鸟舍替换了整个多重不确定动物，这正是对抗性配对引起的不可避免的冲突的最大数量。 由于每个细分在完全揭示和重新安排后都是独立的，因此将细分成本相加得出全局有效的最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    b = list(map(int, input().split()))
    
    cur = 0
    ans = 0
    
    for x in b:
        if x == 1:
            cur += 1
        else:
            ans += (cur + 1) // 2
            cur = 0
    
    print(ans)
```该实现仅保留两个变量，它们直接对应于算法中的状态：`cur`存储当前未解析的块大小，以及`ans`累积由医生就诊分隔的所有街区所需的鸟舍。 

关键的实现细节是公式`(cur + 1) // 2`，它简洁地代表了最坏情况下的成对和单组分组。 重置`cur`每个之后`2`至关重要，因为每次就诊都完全消除了不确定性并允许最佳重组，因此以前的结构不会延续。

 ## 边缘情况

 一个关键的边缘情况是医生就诊之间没有插入。 在这种情况下，段大小为零并且没有任何贡献。 例如，输入`2 2 2`产生`cur = 0`每次，所以每次更新都会添加`(0 + 1)//2 = 0`，如预期的那样产生零答案。 

另一个重要的例子是长时间不间断的插入序列，然后是一次医生就诊。 用于输入`1 1 1 1 1 2`，我们积累`cur = 5`，在揭晓时我们计算`(5 + 1)//2 = 3`。 这符合最坏情况的要求，即最多两只动物只有在性别相同的情况下才能安全地共享一个鸟舍，从而迫使它们与剩下的单一动物配对。 

最后，交替模式，如`1 2 1 2 1 2`确认长度为 1 的每个片段恰好贡献一个鸟舍，并重置以防止任何遗留相互作用。 每个段都是独立的，算法的重置确保过时状态不会影响未来的计算。
