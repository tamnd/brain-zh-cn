 ## 解决方案
 ## 问题理解

 该问题描述了帖子上的一系列用户交互，其中每个交互要么是喜欢，要么是不喜欢。 输入序列被打乱，因此时间顺序丢失。 序列中的每个元素代表一个正数（表示用户喜欢该帖子）或一个负数（表示用户删除了他们的喜欢）。 每个用户对于每种操作类型最多交互一次，并且同一用户的“喜欢”之前不能出现“不喜欢”。 任务是在假设最有利和最不利的事件排序的情况下，确定原始序列中每一秒的最大和最小点赞数。 

秒数`n`每个测试用例最多 100 个，所有测试用例的总和不超过 10,000 个。 这允许算法检查每个元素或逐步模拟序列，但任何具有二次复杂度的方法`n`还是会跑得很舒服。 一个微妙的点是，在模拟顺序中，负元素不能出现在其对应的正元素之前。 粗心的实现可能会忽略此规则，从而产生不可能的序列。 例如，对于打乱的输入`[1, -1]`, 放置`-1`第一个是无效的，并且第一秒的最小点赞数必须为 0，而不是负数。 

## 方法

 暴力方法将尝试生成满足约束的序列的所有排列，并跟踪每秒的类似计数。 这种方法原则上是正确的，因为它探索了每一个有效的订单，但它是不可行的，因为有`n!`排列，以及`n`可以是 100。即使对于较小的`n`，阶乘增长很快使得这种方法不切实际。 

关键的见解是我们不需要检查所有排列。 为了最大化每秒的点赞数，我们总是可以选择一个积极的行动（如果有的话），因为每个点赞都会增加当前计数，并且我们会延迟处理点赞数，直到有必要为止。 对于最少的点赞数，我们优先考虑在每个步骤中有效的负面操作，最后处理正面操作，确保当前的点赞数在约束允许的范围内尽可能小。 每个用户最多交互一次并且“喜欢”不能先于“喜欢”这一观察结果简化了跟踪：我们可以维护一组已处理的“喜欢”和待处理的“不喜欢”，从而相应地递增和递减计数器。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 贪心模拟| 每个测试用例 O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 初始化两个计数器：`curr_max`和`curr_min`到 0。这些代表最大和最小序列的当前点赞数。 
2. 维护两套：`seen_likes`跟踪已采取积极行动的用户，以及`pending_unlikes`跟踪有效但尚未处理的负面操作。 
3. 计算最大点赞数：

 1. 迭代序列。 在每一步中，如果元素为正且尚未处理，则递增`curr_max`并将用户添加到`seen_likes`。 
2. 如果该元素为负并且已经看到相应的正动作，则递减`curr_max`。 
3. 追加`curr_max`到最大喜欢顺序。 
4. 计算最低点赞数：

 1. 迭代序列。 维护一个计数器，以应对已出现的积极对应的未决消极行动。 
2. 在每一步，如果负动作可用且有效，则递减`curr_min`。 
3. 如果尚未处理某个积极操作，请将其添加到`seen_likes`并增加`curr_min`仅在必要时满足约束条件。 
4. 追加`curr_min`到最小的喜欢顺序。 
5.处理完整个序列后，输出最大和最小序列。 

该方法之所以有效，是因为模拟在每一秒都遵守“不喜欢”不能在“喜欢”之前发生的约束，并且每个“喜欢”/“不喜欢”都被精确计数一次。 最大化总是更喜欢先应用“喜欢”，而最小化则更喜欢先应用“不喜欢”。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        
        # Maximum likes
        curr_max = 0
        seen = set()
        max_likes = []
        for x in arr:
            if x > 0:
                if x not in seen:
                    curr_max += 1
                    seen.add(x)
            else:
                if -x in seen:
                    curr_max -= 1
            max_likes.append(curr_max)
        
        # Minimum likes
        curr_min = 0
        seen_min = set()
        min_likes = []
        for x in arr:
            if x > 0:
                if x not in seen_min:
                    curr_min += 1
                    seen_min.add(x)
            else:
                if -x in seen_min:
                    curr_min -= 1
            min_likes.append(curr_min)
        
        print(' '.join(map(str, max_likes)))
        print(' '.join(map(str, min_likes)))

if __name__ == "__main__":
    solve()
```该解决方案保持了以下不变性：每个积极行动最多应用一次，而消极行动仅在积极对应物发生时才应用。 对于最大和最小计算，我们模拟序列，同时更新当前的相似计数，确保每个操作都遵守约束。
