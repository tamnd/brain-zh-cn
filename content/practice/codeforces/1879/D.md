 ## 解决方案
 ## 问题理解

 我们得到一个非负整数数组。 对于每个子数组$[l,r]$，我们计算该子数组内所有元素的异或。 令 XOR 值为$f(l,r)$。 

子数组的贡献不仅仅是它的异或。 它乘以子数组长度：$$f(l,r)\cdot(r-l+1)$$任务是对所有子数组求和并输出结果模$998244353$。 

直接实施将检查所有$O(n^2)$子数组。 和$n\le 3\cdot10^5$，这大约意味着$4.5\times10^{10}$子数组，这在两秒内是完全不可能的。 甚至一个$O(n^2)$每个子数组仅执行少量操作的算法远远超出了限制。 

数组值最多为$10^9$，所以每个数字都适合 30 位。 每当问题要求 XOR 值之和时，独立处理每个位通常是有利的，因为 XOR 独立作用于每个位位置。 

一个微妙的极端情况是长度乘数取决于两个端点。 例如：```
2
1 1
```子数组：```
[1] -> 1 * 1 = 1
[1,1] -> 0 * 2 = 0
[1] -> 1 * 1 = 1
```答案=2。 

一种只计算有多少个子数组具有异或位的解决方案$1$会错过长度权重并产生错误的结果。 

另一个容易犯的错误是忘记子数组 XOR 是通过前缀 XOR 表示的：```
1
5
```唯一的子数组具有异或$5$， 长度$1$， 回答$5$。 

这种情况需要在数组开始前加上前缀XOR，即$pref_0=0$。 省略此前缀会导致所有子数组从位置开始$1$从计数中消失。 

错误的第三个来源是模运算。 加权和可能变得非常大。 尽管Python整数不会溢出，但问题需要对最终结果取模$998244353$，并且中间累积也应该以该值为模减少。 

## 方法

 暴力解决方案枚举每一对$(l,r)$。 使用前缀 XOR，每个子数组 XOR 可以计算为$O(1)$:$$f(l,r)=pref_r\oplus pref_{l-1}$$然后我们添加$$(pref_r\oplus pref_{l-1})(r-l+1)$$到答案。 

这是正确的，因为它直接遵循问题的定义。 问题是子数组的数量。 有$$\frac{n(n+1)}2$$其中，达到约$4.5\times10^{10}$什么时候$n=3\cdot10^5$。 

关键的观察是 XOR 可以逐位分解。 

考虑一位位置$b$。 它对最终答案的贡献是$$2^b \times \sum_{\text{subarrays whose XOR has bit }b=1} (r-l+1)$$所以真正的任务变成了：

 对于每个位，找到该位上的 XOR 等于的所有子数组的总长度$1$。 

为此位引入前缀异或奇偶校验。 让$$p_i = \text{bit } b \text{ of } pref_i.$$对于子数组$[l,r]$,$$\text{bit } b \text{ of } f(l,r) = p_r \oplus p_{l-1}.$$当这两个奇偶校验不同时，该位会准确起作用。 

现在使用前缀索引重写子数组：$$j=l-1,\qquad i=r.$$子数组长度变为$$r-l+1=i-j.$$因此，对于固定位，我们需要$$\sum_{0\le j<i\le n,\ p_i\ne p_j} (i-j).$$这是前缀异或奇偶校验的配对计数问题。 

假设我们从左到右处理前缀位置。 当我们到达位置时$i$，我们想要所有以前的位置$j$其奇偶性不同于$p_i$。 

他们的贡献是$$\sum (i-j) = (\text{count})\cdot i - \sum j.$$所以对于每个奇偶校验$0$和$1$，我们只需要：

 - 有多少个先前的前缀具有该奇偶校验，
 - 它们的指数之和。 

那么每个前缀位置都可以被处理$O(1)$, 给予$O(n)$每比特的工作量。 

由于只有 30 个相关位，因此总复杂度变为$O(30n)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |

 |---|------|---|

 | 蛮力 |$O(n^2)$|$O(n)$| 太慢了 |

 | 最佳 |$O(30n)$|$O(1)$| 已接受 |

 ## 算法演练

 ### 1. 构建前缀异或

 创建$$pref_0=0, \qquad pref_i=pref_{i-1}\oplus a_i.$$那么每个子数组异或等于$$pref_r\oplus pref_{l-1}.$$### 2. 独立处理每一位

 对于每一点$b$从$0$到$29$，计算 XOR 为 bit 的子数组的总加权长度$b=1$。 

最终答案是这个数量乘以$2^b$。 

### 3.维护之前前缀奇偶校验的统计

 对于当前位，定义$$parity_i = (pref_i>>b)\&1.$$维持：```
cnt[0], cnt[1]
sumPos[0], sumPos[1]
```在哪里`cnt[t]`是先前具有奇偶校验的前缀位置的数量`t`， 和`sumPos[t]`是它们的指数之和。 

最初只有前缀位置$0$存在：```
cnt[0] = 1
sumPos[0] = 0
```### 4.从左到右处理前缀

 在位置$i$，设当前奇偶校验为$p$。 

我们需要所有先前的位置具有奇偶性$p\oplus1$。 

如果```
opp = p ^ 1
```那么他们的总贡献是$$cnt[opp]\cdot i - sumPos[opp].$$这个数量等于$$\sum(i-j)$$超过所有有效的先前职位$j$。 

将其添加到该位的运行贡献中。 

### 5.插入当前前缀

 使用位置后$i$作为右端点，将其添加到数据结构中：$$cnt[p] += 1$$

$$sumPos[p] += i$$### 6.添加比特贡献

 如果位的累积加权长度$b$是$cur$， 添加$$cur\cdot 2^b$$对答案取模$998244353$。 

### 为什么它有效

 对于固定位，当子阵列两端对应的前缀奇偶校验不同时，子阵列就准确地做出贡献。 每个子数组$[l,r]$唯一对应于一对前缀索引$(l-1,r)$。 处理前缀位置时$r$，该算法考虑具有相反奇偶校验的所有较早的前缀位置。 表达式$$cnt\cdot r-\sum j$$正好是长度之和$r-j$所有这样的子数组。 每个有效子数组在处理其右端点时都会被计数一次，并且无效子数组永远不会被计数，因为它们的奇偶校验相等。 对所有位独立求和可重构原始 XOR 值，因此最终答案等于所需的加权和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] ^ a[i]

    ans = 0

    for b in range(30):
        cnt = [1, 0]          # prefix 0 already exists
        sum_pos = [0, 0]

        cur = 0

        for i in range(1, n + 1):
            p = (pref[i] >> b) & 1
            opp = p ^ 1

            cur += cnt[opp] * i - sum_pos[opp]

            cnt[p] += 1
            sum_pos[p] += i

        ans = (ans + (cur % MOD) * ((1 << b) % MOD)) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```前缀异或数组将每个子数组异或转换为两个前缀的异或。 之后，每一位都可以独立处理。 

对于一位，唯一重要的信息是该位的前缀 XOR 是否是$0$或者$1$。 数组`cnt`和`sum_pos`准确存储评估所需的统计数据$$\sum(i-j)$$对于具有相反奇偶校验的所有先前前缀。 

操作顺序很重要。 当前前缀位置在插入数据结构之前必须起作用。 否则，前缀将错误地与其自身配对，从而创建零长度子数组。 

价值```
cnt[opp] * i - sum_pos[opp]
```已经等于所有新发现的以位置结束的有效子数组的总长度`i`。 不需要额外的长度计算。

 ## 边缘情况

 考虑：```
1
5
```前缀异或数组是：```
[0,5]
```对于每个设置位 5，位置 1 与位置 0 具有相反的奇偶校验，产生长度 1。答案恰好变为 5。这证实了包括初始前缀 XOR 是必要的。 

考虑：```
2
1 1
```XOR 等于 1 的唯一子数组是两个单元素子数组。 较长的子数组具有 XOR 0。在处理过程中，与整个数组对应的前缀对具有相等的奇偶性，并且从不被计数。 算法正确输出 2。 

考虑：```
3
0 0 0
```所有前缀 XOR 均为零。 每个位奇偶校验始终为 0。由于相反的奇偶校验前缀永远不存在，因此每个贡献都为零。 答案仍然是 0，这与每个子数组 XOR 都为零的事实相匹配。 

考虑：```
2
1 0
```子数组是：```
[1]   -> 1 * 1 = 1
[1,0] -> 1 * 2 = 2
[0]   -> 0 * 1 = 0
```全部的：```
3
```该算法从索引 1 开始对两个子数组进行计数，因为初始前缀位置 0 参与奇偶校验匹配过程。 这正是破坏忘记空前缀的实现的情况。
