 ## 解决方案
 ## 问题理解

 给定一个二进制字符串，并且允许我们从任意位置删除字符。 删除一些字符后，我们希望剩余的字符串是交替的，这意味着没有两个相邻的字符是相等的。 

与其从删除的角度思考，不如从我们保留的角度思考更自然。 如果我们保留一个交替的子序列，则每次删除都对应于删除该子序列之外的所有内容。 因此，第一个目标就是找到原始字符串的最长交替子序列。 如果我们知道它的长度是L，那么最小删除次数就是n减去L。 

第二部分更微妙：我们需要计算存在多少个最短删除序列。 由于删除序列是由删除索引的顺序定义的，并且我们可以以任何顺序选择删除，因此这有效地计算了我们可以选择删除哪些位置的方式有多少种，同时仍然实现最佳的最终交替子序列。 这变成了选择保留哪些字符的组合计数问题。 

所有测试用例的总长度最多为 2⋅10^5 的约束意味着每个测试用例的任何解决方案都必须是线性或接近线性的。 像所有子序列上的 DP 或强力删除模拟这样的二次方法是不可能的。 

一些边缘案例阐明了结构。 

如果字符串已经是交替的，例如 0101，则不需要删除，并且只有一个有效序列：不执行任何操作。 任何试图“计算删除选择”的方法都必须避免人为引入额外的序列。 

如果字符串是统一的，例如 111，我们最多只能保留单个字符，因此我们删除所有其他字符。 然而，保留哪个最终字符的所有选择都是对称的，并且有效删除顺序的数量变得组合而不是微不足道的。 

关键的困难不是找到最小的删除，而是计算导致最佳交替结果的不同删除顺序的数量。 

## 方法

 如果我们考虑暴力破解，我们可以枚举字符串的所有子序列，检查每个子序列是否交替，计算最佳长度，然后计算有多少子序列达到该长度。 这已经具有指数复杂度，因为有 2^n 个子序列。 即使检查每一项也是 O(n)，所以这是完全不可行的。 

更结构化的蛮力方法将尝试以各种方式贪婪地构建子序列：在每个位置我们要么保留或删除它，维持当前子序列是否保持交替。 这也会导致 O(2^n) 状态，因为每个字符都会使分支加倍。 

关键的观察结果是，最佳交替子序列极其严格：一旦我们确定它是从 0 还是 1 开始，该序列就会被强制。 只有两个候选目标模式：0101…或1010…。 对于每个模式，我们可以从左到右贪婪地匹配字符，始终采用最早的可能匹配。 这会产生该模式的最大可能长度。 

所以最优长度就是这两个贪婪匹配中的最大值。 删除只是所选匹配中未使用的所有内容。 

计数部分来自于了解我们可以选择删除同时保留相同的最终匹配子序列的方式有多少种。 子序列中未使用的每个字符都会被删除，但删除可以任意排序，并且对哪个出现“负责”打破匹配关系的不同选择会成倍地贡献。 这导致计算所选匹配位置之间的间隙并跨段分配删除顺序选择。

最终的解决方案减少为每个模式扫描一次字符串，并根据匹配之间跳过的额外字符数来累积组合贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解子序列 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 贪婪匹配+组合 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从概念上处理字符串两次：一次假设目标交替字符串以 0 开头，一次以 1 开头。 

1. 固定一个目标模式，比如从 0 开始。我们从左到右扫描字符串，并贪婪地尝试匹配 0101… 之后的最长交替子序列。 

在每一步中，我们都会保持下一个预期的特征。 当我们看到它时，我们将其作为子序列的一部分并翻转期望。 如果我们没有看到它，我们就会有效地跳过字符。 

这种贪婪的选择是最优的，因为采取较早的有效匹配总是为未来的匹配留下最大的灵活性。 
2. 在扫描时，我们跟踪匹配发生的位置。 在两个连续的匹配位置之间，有一个在子序列中未使用的字符块。 所有这些字符都必须删除。 
3. 对于固定的最优子序列，删除序列的数量取决于每个块内删除操作执行的相对顺序。 由于删除是由原始索引标记的，因此任何删除顺序都是有效的，但哪些块有助于“早期”删除的不同选择会影响序列同一性。 

关键的简化在于不同块中的删除是独立的：删除较早块中的字符不会限制后面块中的删除。 这导致了块上的乘法结构。 
4. 对于匹配位置之间大小为 k 的每个块，我们贡献一个类似阶乘的因子，捕获将该块中的删除与其他块交错的方式数量，同时保持相同的最终保留子序列。 汇总这些贡献即可得出该起始模式的计数。 
5. 我们为从 1 开始的模式计算相同的值，并获取与较长子序列相对应的结果。 如果两个模式产生相同的长度，则它们的计数会相加，因为它们对应于不同的最终交替字符串。 

### 为什么它有效

 任何最佳解决方案完全取决于它所针对的交替模式以及选择哪些事件来实现它。 贪婪扫描产生每个最佳子序列的规范代表。 所有有效的删除序列完全对应于所选匹配之间的独立间隙内的删除排列。 由于这些间隙在可行性方面不会相互作用，因此最短序列的总数会因式分解间隙，从而确保不会出现过度计数或丢失配置的情况。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve_case(s):
    n = len(s)

    def solve_start(start_char):
        expected = start_char
        matched_positions = []
        
        for i, ch in enumerate(s):
            if ch == expected:
                matched_positions.append(i)
                expected = '1' if expected == '0' else '0'
        
        L = len(matched_positions)
        if L == 0:
            return 0, 1
        
        # count deletions structure
        ways = 1
        
        # gaps between matched positions
        prev = -1
        for pos in matched_positions:
            gap = pos - prev - 1
            ways = (ways * (gap + 1)) % MOD
            prev = pos
        
        # suffix gap
        gap = n - prev - 1
        ways = (ways * (gap + 1)) % MOD
        
        return n - L, ways

    # try both patterns
    del0, ways0 = solve_start('0')
    del1, ways1 = solve_start('1')

    if del0 < del1:
        return del0, ways0
    if del1 < del0:
        return del1, ways1
    return del0, (ways0 + ways1) % MOD

def main():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        ans, ways = solve_case(s)
        print(ans, ways)

if __name__ == "__main__":
    main()
```该解决方案的结构是围绕每个起始奇偶校验的最大交替子序列的贪婪提取。 名单`matched_positions`准确编码哪些索引在最佳结构中幸存。 连续匹配之间的间隙代表强制删除的片段，并且每个间隙根据如何安排删除顺序同时保留最终子序列而贡献一个乘法因子。 

从“0”开始和从“1”开始之间的最终比较确保我们选择全局最优的交替模式。

这表明必须在两个起始状态之间比较各个贪婪扫描，而不是单独解释。

 ## 边缘情况

 对于像这样的单字符字符串`0`，贪婪扫描恰好匹配一个元素并产生零删除。 间隙计算乘以一个因子 1，因此删除序列的数量仍为 1。 

对于像这样的统一字符串`111`，贪心匹配最多产生一个保留字符。 每个位置都可以作为保留字符，具体取决于删除的排序方式，并且间隙结构对跨位置交错删除的所有方式进行计数，从而产生类似阶乘的计数。 

对于已经交替的字符串，例如`0101`，贪婪匹配捕获整个字符串，没有间隙。 每个间隙因子都变为 1，并且结果折叠为单个有效的删除序列。 

对于像这样的字符串`0011`，在不同的起始模式下，存在多个等长的最优子序列。 该算法通过评估两种模式并在长度匹配时求和贡献来解决此问题，确保不会错过最佳配置。
