 ## 解决方案
 ## 问题理解

 我们得到一个以字符串形式写的十进制数和一个额外的数字。 我们可以在号码中的任何位置插入该数字，包括第一个数字之前或最后一个数字之后。 目标是选择插入位置，以便得到的数字（通常以 10 为基数解释，前导零没有特殊情况）尽可能大。 

关键的心理模型是，我们将一个字符插入到一个字符串中，并希望得到字典顺序上最大的可能结果字符串，因为逐位比较两个等长的十进制字符串与非负整数的数字比较相匹配。 

测试用例的输入大小很大，所有数字的总长度最多可达 200,000。 这立即表明，任何独立尝试每个插入位置并重复重建完整字符串的解决方案，只有在每个测试用例都是线性的情况下，总体上仍然是好的。 每个测试用例的任何二次方都会在最坏情况的输入下崩溃。 

一种简单的方法可能会尝试在每个 n+1 个位置插入数字，每次构造结果字符串，然后比较所有结果。 在最坏的情况下，由于重复的字符串构造和比较，每个测试用例的成本已经是 O(n^2)。 由于测试中的总 n 高达 2e5，这太慢了。 

有一些边缘情况打破了粗心的贪婪直觉。 一种是当额外的数字很小时，例如将 1 插入到像 98765 这样的降序数字中。总是追加将是错误的，因为提前插入会产生更大的数字。 另一种情况是当数字等于插入的数字时，例如将 5 插入 5555，其中位置并不重要，但如果条件在错误的方向上严格，则差一插入规则很容易改变正确性。 最后的边缘情况是插入 0，其中位置仍然很重要，因为原始版本中不允许使用前导零，但允许作为中间结构的一部分； 正确性完全取决于字典顺序的最大化。 

## 方法

 蛮力方法会尝试所有可能的插入点。 对于从 0 到 n 的每个位置 i，我们通过插入数字来构造一个新字符串，并将其与迄今为止看到的最佳字符串进行比较。 这是正确的，因为它显式评估所有有效配置。 失败点是性能。 每次插入的构建成本为 O(n)，比较成本为 O(n)，每个测试用例的成本为 O(n^2)。 总共超过 2e5 个字符，这变得太慢了。 

问题的结构允许更简单的观察。 我们将一位数字插入到固定字符串中，并且希望结果字符串按字典顺序尽可能大。 这意味着我们希望插入的数字尽可能靠左，同时仍保持最大排序。 如果我们从左向右移动数字，只要现有数字大于或等于插入的数字，我们就应该保留它们，因为将数字放在它们后面会保留更大的前缀。 当前数字严格小于插入数字的第一个位置就是我们应该插入的位置。 

如果我们找不到这样的位置，则意味着所有数字都大于或等于插入的数字，因此最佳位置在末尾。 

这将问题简化为单个线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。

1.读取字符串number和数字d，转换为字符。 使用字符可以避免重复的整数转换并直接与字典比较对齐。 
2. 初始化一个空结果列表和一个指示是否已插入数字的标志。 
3. 从左到右扫描原始号码。 在每个位置，将当前数字与 d 进行比较。 
4. 当当前数字大于或等于 d 时，我们将其附加到结果中。 我们这样做是因为将 d 放在前面会使前缀在字典顺序中更小。 
5. 一旦找到严格小于 d 的数字，我们就在该位置插入 d，将其附加到结果中，然后附加原始数字的其余部分。 
6. 如果到达末尾但没有插入 d，则将其附加到末尾。 

关键的决策点是严格的不平等。 如果当前数字等于 d，我们仍然推迟插入，因为稍后放置 d 会保留前缀并且不会减少结果数字。 

其工作原理：在扫描中的任何一点，已附加到结果中的所有数字都保证其位置最佳。 放置 d 改进前缀的第一个位置正是现有数字小于 d 的位置。 任何较晚的插入都会比必要的更早地减少前缀，并且任何较早的插入都会替换更大或相同的数字，这不能增加最终的词典编排值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, d = input().split()
        s = input().strip()

        inserted = False
        res = []

        for ch in s:
            if not inserted and ch < d:
                res.append(d)
                inserted = True
            res.append(ch)

        if not inserted:
            res.append(d)

        out.append("".join(res))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现直接遵循前面描述的贪婪扫描。 为了提高效率，结果是使用列表构建的，否则重复的字符串连接会将性能降低到二次行为。 每个字符进行一次插入检查，确保线性复杂性。 

一个微妙的点是，当我们检测到 ch < d 时，插入发生在附加当前字符之前。 这保留了正确性，因为数字必须严格出现在第一个较小数字之前。 如果我们先追加然后插入，我们就会错误地将位置移动一位。

 ## 边缘情况

 关键的边缘情况是所有数字都等于插入的数字。 用于输入`44444`和`d = 4`，扫描永远不会找到严格小于 4 的数字，因此插入发生在末尾。 该算法首先附加所有数字，然后附加 4，产生`444444`，这是正确的，因为任何较早的插入都会产生相同的多组数字，但顺序相同，并且该规则仍然一致地将数字放置在最后一个有效位置。 

另一种边缘情况是插入的数字为 0 时。例如，插入`7058959`，算法将 0 放置在第一个小于 0 的数字处，但这种情况永远不会发生，因此将其附加在末尾。 这是正确的，因为前导位置插入只会减少字典顺序值，因为 0 是最小的数字。 

最后的边缘情况是插入的数字是最大可能的数字 9。`12345`，第一个数字 1 小于 9，所以我们立即插入到前面，产生`912345`。 这证实了贪婪规则正确地优先考虑了最大化最高有效数字位置。
