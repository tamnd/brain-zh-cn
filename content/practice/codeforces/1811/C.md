 ## 解决方案
 ## 问题理解

 我们得到一个派生数组$b$，我们被告知它来自一些隐藏数组$a$。 各值$b_i$是两个相邻值中的最大值$a$， 具体来说$a_i$和$a_{i+1}$。 我们的任务不是唯一地重建原始数组，而是构造任意有效的数组$a$可能会产生给定的$b$。 

问题的结构是局部的。 每个约束仅关联两个相邻位置$a$，所以整个系统是一个重叠的最大约束链。 输出只是满足所有这些局部最大值关系的任何非负整数数组。 

约束允许最多$2 \cdot 10^5$跨测试用例的总元素，这立即排除了任何二次或大量模拟的重建。 任何试图独立地对每个职位的候选人进行暴力的行为至少会导致$O(n^2)$最坏情况下的行为，远远超出了极限。 每个测试用例的解决方案必须是线性的。 

当出现微妙的边缘情况时$b$包含重复值或长平坦段。 一个天真的想法可能是直接将每个约束的两个端点设置为$b_i$，但这可能会违反相邻约束，因为中的每个位置$a$参与两个不同的最大值。 当出现零时会发生另一种失败情况，因为零可以在没有显式分配的情况下传播约束，并且粗心的填充可能会意外引入不必要的正值。 

## 方法

 暴力尝试将尝试构造所有可能的数组$a$符合$b$，检查每个候选是否满足所有最大约束。 即使我们将值限制为出现在$b$，每个位置仍然有多种选择，状态空间呈指数级增长。 为了$n = 2 \cdot 10^5$，即使每个元素的二元决策也会导致$2^n$的可能性，这显然是不可行的。 

关键的观察是每个$b_i$只强制执行至少其中一项$a_i$或者$a_{i+1}$等于$b_i$，并且两者都不能超过它。 这意味着每个位置$a_i$受到两个邻居的约束：$b_{i-1}$和$b_i$。 如果我们本地化思考，$a_i$必须足够小，以便不违反任何一个相邻的最大值，但又足够大，以便通过适当选择另一个端点仍然可以满足这两个约束。 

这导致了一种建设性的贪婪策略：为每个位置分配仍然与两个相邻约束兼容的最小值，同时确保每对中的至少一个端点可以实现所需的最大值。 实现此目的的一个直接而干净的方法是初始化所有$a_i$为零，然后有选择地将所需的最大值“注入”到需要的位置，确保每个$b_i$由至少一个端点实现。 

更系统的构建是对待每一个$b_i$作为必须出现在任一位置的需求$i$或者$i+1$，然后贪婪地将其分配到仍然灵活的位置。 由于每个位置最多参与两个约束，因此从左到右的传递足以保证一致性。

 ## 算法演练

 1.初始化一个数组$a$长度$n$全为零。 这给出了一个中立的基线，永远不会违反任何最大约束。 
2. 对于每个索引$i$，考虑约束$b_i = \max(a_i, a_{i+1})$。 我们必须确保两个位置中至少有一个具有价值$b_i$。 
3. 如果两者都$a_i$和$a_{i+1}$目前小于$b_i$， 分配$a_{i+1} = b_i$。 这种选择保留了左侧未来的灵活性，同时保证满足约束。 
4. 如果端点之一已经等于$b_i$，什么也不做，因为约束已经满足。 
5.全部处理完毕后$b_i$，返回数组$a$。 

关键的设计选择始终是在需要时将值推向右侧。 这避免了过早地固定左侧位置，而仍然需要这些位置来满足早期的约束。 

### 为什么它有效

 每个约束$b_i$只处理一次，并且在处理时，我们保证至少有一个端点匹配$b_i$。 因为我们的价值永远不会超出$b_i$，在满足任何约束条件后，我们不会违反任何约束条件。 贪婪方向确保未来的约束总是看到有效的前缀，如果需要，仍然可以在右侧进行调整。 这创建了一个一致的链，其中每个最大要求都在本地得到满足，而不会破坏早期的决策。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    b = list(map(int, input().split()))
    
    a = [0] * n
    
    for i in range(n - 1):
        if a[i] < b[i] and a[i + 1] < b[i]:
            a[i + 1] = b[i]
    
    print(*a)
```该解决方案从零初始化数组开始，确保不会意外违反约束。 然后，它从左到右处理每个约束，强制执行每个约束$b_i$必要时将其值放入正确的端点。 这种方向性至关重要，因为它可以防止覆盖早期强制的约束。 

一个常见的错误是尝试对称分配双方或回溯更新。 这导致了重叠约束之间的矛盾。 贪婪的一次性方法完全避免了这种情况。

 ## 边缘情况

 一个关键的边缘情况是当所有值都在$b$为零。 在这种情况下，正确的输出是全零数组。 该算法从零开始并且从不触发任何赋值，因此它正确地保留了该结构。 

另一种情况是当$b$是严格增加的。 每个新值都会强制向右分配新的值，而较早的值保持不变。 贪婪策略确保每次增加都是独立处理的，不会发生冲突。 

第三种情况是单元素$b$，其中任何一对相等的值都是有效的。 该算法仅在必要时进行分配，因此它自然会产生有效的对，无需特殊处理。
