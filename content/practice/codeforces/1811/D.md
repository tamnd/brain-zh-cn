 ## 解决方案
 ## 问题理解

 我们得到一个矩形，其尺寸与斐波那契数相关。 它的高度是$F_n$它的宽度是$F_{n+1}$，斐波那契数列开始于$F_0 = F_1 = 1$。 在该网格内，标记了一个特定的单元格。 任务是决定是否可以将整个矩形精确地划分为$n+1$使得每个正方形的边长都是斐波那契数，并且标记的单元格必须最终位于单位正方形内。 在分区中使用的所有方格中，最多可以有一个重复的大小。 

输出是可行性决策：对于每个测试用例，我们回答是否存在这样的分解。 

这些约束立即排除了每个测试用例的任何直接构造。 高达$2 \cdot 10^5$查询和$n \le 44$，任何模拟平铺或递归地构造每个查询区域的方法都必须在预处理后减少为常数或对数工作。 斐波那契值增长很快，因此坐标可能很大，但仍然可以轻松地适合 64 位整数，这表明解决方案的结构仅取决于相对定位，而不取决于显式网格表示。 

一个微妙的困难出现在标记单元如何与递归分解相互作用。 该矩形不是任意的，它具有规范的斐波那契分解为两个较小的斐波那契矩形。 恰好一个单位正方形必须包含标记单元的约束强制了通过此分解的确定性路径，但是当标记单元位于两个子矩形都是合理延续的边界附近时，天真的贪婪选择可能会失败。 

朴素推理的一个具体失败案例是，假设在每一步我们总是下降到“更大”的子矩形而不检查哪一侧包含目标单元格。 对于像这样的情况，这会立即中断$n=3$，其中错误的分割选择可能会将标记的单元格放置到一个区域中，该区域随后无法生成与全局方块数一致的有效单位方块放置。 

另一种失败模式是忽略“至多一对相同大小的正方形”的约束。 由于斐波那契数严格递增，因此在有效分解中重复很少见，并且假设任意重复会导致接受无效结构。 

## 方法

 蛮力视角试图明确模拟如何切割斐波那契矩形。 定义身份$F_{n+1} = F_n + F_{n-1}$建议$F_n \times F_{n+1}$矩形可以垂直或水平分割成更小的斐波那契矩形，继续递归直到达到单位正方形。 简单的递归会在每个级别尝试两种可能的分割，跟踪标记单元格的位置，并对生成的方块进行计数。 

这种方法原则上是正确的，因为它探索了斐波那契平铺的完整分解树。 然而，分支因子导致指数增长。 虽然$n \le 44$，如果只要存在歧义就考虑两个分割选择，每个测试用例仍然可以探索一个大的状态空间。 最坏的情况会退化为探索基本上所有的斐波那契平铺树，这对于$2 \cdot 10^5$测试用例。 

关键的观察结果是斐波那契矩形具有严格的规范结构。 在每一步中，矩形都会以固定方向分解为两个较小的斐波那契矩形。 唯一的自由是哪个子矩形包含标记的单元格。 一旦决定了这个选择，剩下的分解就被迫进行。 这完全消除了分支。 

因此，问题简化为重复将标记的单元映射到较小的斐波那契矩形，根据它位于分割的哪一侧更新其坐标，并继续直到到达矩形所在的基本情况$1 \times 1$。

 ## 算法演练

 我们预先计算斐波那契数直到索引 44，因为所有维度都依赖于它们。 

然后我们按顺序模拟矩形的结构$n$向下。 

1.从一个大小的矩形开始$F_n \times F_{n+1}$和一个标记的单元格$(x, y)$。 
2. 订购时$n$，矩形分成两个斐波那契矩形：其中一个尺寸$F_{n} \times F_{n-1}$和另一个尺寸$F_{n-1} \times F_{n}$，排列成固定的L形平铺。 所有结构的确切方向都是一致的，因此唯一相关的问题是标记的单元格位于第一部分还是第二部分。 
3. 如果标记的单元格位于第一个子矩形中，我们将其映射到该矩形而不更改坐标。 如果它位于第二个块中，我们通过减去第一个块沿适当轴的偏移量将坐标移动到该子矩形的局部系统中。 
4.我们减少$n$1 并重复该过程，因为每一步都将问题简化为更小的斐波那契矩形。 
5. 继续直到$n = 1$，此时矩形为$1 \times 2$或者$2 \times 1$取决于索引，标记的单元格必须以与结构一致的单位正方形配置结束。 

如果我们能够始终遵循这条强制路径而不会遇到不可能的坐标转换，则该决定是有效的。 

### 为什么它有效

 斐波那契矩形允许直接源自的独特递归平铺结构$F_{n+1} = F_n + F_{n-1}$。 在每一步中，分解都会将区域精确地划分为两个较小的斐波那契矩形，它们的并集是不相交且完整的。 由于在最终分解中标记的单元必须恰好保留在一个单位正方形内，因此它的位置唯一地确定哪个子矩形在每个级别都是相关的。 

这种独特性消除了所有组合选择。 与强制路径的任何偏差都意味着将标记的单元放置到无法细化为有效的完整平铺的区域中$n+1$正方形，违反覆盖范围或大小限制。 因此，贪心下降既是必要的，也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    F = [0] * 50
    F[0] = F[1] = 1
    for i in range(2, 45):
        F[i] = F[i - 1] + F[i - 2]

    t = int(input())
    for _ in range(t):
        n, x, y = map(int, input().split())

        ok = True

        # We simulate descending through Fibonacci rectangles
        while n > 1:
            fn = F[n]
            fn1 = F[n - 1]

            # rectangle is fn x fn+1
            # split into fn x fn-1 and fn-1 x fn

            if y <= fn1:
                # left/top part (fn x fn-1), coordinates unchanged
                pass
            else:
                # right/bottom part (fn-1 x fn), shift coordinates
                y -= fn1
                x = x - fn + fn1  # map into rotated subrectangle (consistent orientation)

            n -= 1

        # final check: must land in unit configuration
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```该代码首先预先计算斐波那契数，以便可以在 O(1) 内访问每个矩形维度。 对于每个测试用例，我们反复将矩形缩小一个斐波那契水平。 

关键的实现细节是当标记的单元落入第二个子矩形时处理坐标映射。 减法对应于在移除第一个块之后移入该子矩形的局部坐标系。 

一个常见的陷阱是忘记分裂根据奇偶校验来交替方向$n$。 如果忽略这一点，坐标漂移将不正确，并且模拟会接受无效配置。

 该轨迹显示了算法如何确定性地将单元格路由到更小的斐波那契矩形中，而不会产生歧义。 

现在考虑这样一种情况，标记的单元格位于每一步的第一个子矩形中。 坐标保持不变，同时$n$减少，这表明当没有发生边界跨越时，结构保留了局部性。

 ## 边缘情况

 当标记的单元恰好位于两个斐波那契子矩形之间的边界上时，就会出现临界边缘情况。 在这种情况下，不正确的实现可能会不一致地选择一侧，从而导致无效的坐标更新。 正确的处理是确定性分区，其中边界单元始终通过构造分配给第一个子矩形。 

另一个微妙的情况出现时$n$很小，特别是$n=2$或者$n=3$，其中矩形退化为非常小的斐波那契维度。 索引斐波那契数中的任何差一错误都会立即翻转这里的正确性，因为在更深的递归中没有纠错的空间。 

最后一种边缘情况是重复班次累积。 由于每个步骤都可能重新定位坐标，因此错误的方向会在迭代中翻转复合物。 正确的模拟通过始终表示相对于当前矩形而不是全局网格的坐标来避免累积错误。
