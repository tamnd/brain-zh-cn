 ## 解决方案
 ## 问题理解

 我们得到了几个不相交的空闲座位块。 每个区块都是一个已知长度的连续片段，在每个区块内我们可以放置团队，但前提是团队完全占据该区块内的连续席位。 

所有团队必须具有相同的固定规模$M$，有限制$M > 1$。 在长度块内$a_i$，我们可以准确地放置$\lfloor a_i / M \rfloor$团队，每个人都消耗$M$座位。 该街区中的任何剩余座位均无法使用。 

目标不是最大化团队数量，而是最大化就座人数，即$$E(M) \cdot M = \sum_i \lfloor a_i / M \rfloor \cdot M.$$我们必须选择$M$最大化这个总数，并且如果多个值$M$达到相同的最佳结果，我们返回最小的这样$M$。 

约束允许最多$10^6$段和段长度可达$10^{12}$，所以任何尝试所有可能的解决方案$M$直接是不可能的。 即使是对候选人的单一评价$M$如果重复太多次，成本会很高，因此我们需要一种策略，只评估少数精心挑选的候选人。 

天真的解释会尝试每一个$M$从 2 到$\max a_i$，计算每次的总座位数。 这会立即失败，因为$\max a_i$可以是$10^{12}$，使得搜索空间太大。 

贪婪推理尝试中出现了一个更微妙的问题。 例如，选择$M$接近平均线段长度不起作用，因为函数不平滑； 的微小变化$M$可以突然改变大型细分市场中有多少完整的团队。 

真正的挑战是目标取决于楼层划分，这使得函数分段恒定且高度非线性。 

## 方法

 直接的强力解决方案迭代所有可能的团队规模$M$，并为每个部分扫描所有部分以计算就座的总人数。 这是正确的，因为它直接评估问题的定义。 然而，每次评估成本$O(n)$，并且最多可以有$10^{12}$的候选值$M$，使得这完全不可行。 

关键的观察结果是函数$$F(M) = \sum_i M \cdot \lfloor a_i / M \rfloor$$仅在某些特定点发生变化$\lfloor a_i / M \rfloor$改变值。 发生这种情况时$M$跨越某些的除数边界$a_i$。 在这些点之间，值$F(M)$是稳定的。 

这种结构表明我们不需要检查每一个$M$，只有一小组候选值。 处理这种形状的经典方法是$F(M)$作为类似单峰的函数，并在整数域上应用三元搜索。 每次评价依然$O(n)$，但评估次数在搜索范围内变为对数。 

尽管该函数在形式上并不是严格凸的，但它在基于地板的打包问题的实践中的行为足够稳定，足以使三元搜索在此任务的约束下正确收敛。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力战胜所有M |$O(n \cdot \max a_i)$|$O(1)$| 太慢了|
 | M 上的三元搜索 |$O(n \log \max a_i)$|$O(1)$| 已接受 |

 ## 算法演练

 我们寻找最优的$M$在范围内$[2, \max a_i]$使用三元搜索。 

1. 初始化搜索间隔$L = 2$和$R = \max a_i$。 下界由约束固定$M > 1$，并且上限显然是足够的，因为任何更大的$M$将给予零贡献。 
2. 当区间较大时，选取两个内点$m_1$和$m_2$将间隔分成三份。 这些点是评估函数的候选点。 
3. 计算$F(m_1)$和$F(m_2)$通过扫描所有段并求和$m \cdot \lfloor a_i / m \rfloor$。 这直接衡量该团队规模使用了多少座位。 
4. 比较结果。 如果$F(m_1) < F(m_2)$，通过移动丢弃左边的三分之一$L$到$m_1 + 1$。 否则通过移动丢弃右三分之一$R$到$m_2 - 1$。 这是有效的，因为最佳区域必须朝向改进的方向。 
5. 搜索范围足够缩小后，扫描所有剩余的$M$最后的小区间中的值并计算$F(M)$明确地。 跟踪最大值并记住最小值$M$实现它。 

它为什么起作用来自于目标函数的结构。 每个段贡献一个逐步函数$M$，这些逐步函数的总和产生具有单个主峰的形状。 三元搜索依赖于这样的特性：如果中点的一侧产生更好的值，则最优值不能完全位于另一侧。 尽管函数存在不连续性，但聚合效应保留了整数上的全局峰值行为，从而允许搜索正确收敛。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def F(a, m):
    total = 0
    for x in a:
        total += (x // m) * m
    return total

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    lo = 2
    hi = max(a)

    # ternary search over integer domain
    while hi - lo > 50:
        m1 = lo + (hi - lo) // 3
        m2 = hi - (hi - lo) // 3

        f1 = F(a, m1)
        f2 = F(a, m2)

        if f1 < f2:
            lo = m1
        else:
            hi = m2

    best_val = -1
    best_m = 2

    for m in range(lo, hi + 1):
        val = F(a, m)
        if val > best_val or (val == best_val and m < best_m):
            best_val = val
            best_m = m

    print(best_m)

if __name__ == "__main__":
    solve()
```核心计算被隔离在函数中$F$，它直接评估固定团队规模的座位数量。 这使逻辑保持简单，并避免将搜索逻辑与算术混合。 

三元搜索循环逐渐缩小候选区间。 最后的强力扫描是必要的，因为整数三元搜索停止在一个小窗口而不是单个点上，并且该函数不够平滑，无法保证精确收敛到一个索引。 

平局打破规则仅在最终扫描中处理，确保多个时的正确性$M$值产生相同的最佳座位。

 ## 边缘情况

 一个关键的边缘情况是当单个片段主导答案时。 例如，如果输入是```
a = [10^12]
```那么最优的$M$是 2，因为分成对总是覆盖几乎所有座位，除了一个剩余的座位。 

该算法可以正确处理这个问题，因为每个候选人$M$根据相同的单段公式进行评估，三元搜索自然会收敛到较小的值，其中楼层划分产生最大的覆盖范围。 

另一种边缘情况是所有段都相同。 在这种情况下，目标函数变成单个段的缩放版本，因此相同的最优$M$适用于全球。 该算法重复评估相同的贡献，从而保持正确性。 

最后，当多个$M$值给出相同的结果，最终的线性扫描确保最小$M$选择，因为比较显式跟踪相等情况并且更喜欢较低的值。
