 ## 问题理解

 我们得到一棵有根树，以顶点 0 作为根，顶点从 1 到 n。 每个非根顶点都只有一个父顶点，因此该结构已经固定为有根树。 我们还被告知哪些顶点是“关键”顶点，并且树的每个叶子都保证是关键顶点。 

任务是为从父级到子级的每条边分配一个小写英文字母。 一旦分配了字母，每个顶点都会定义一个字符串：根代表空字符串，每个子节点将其边缘字符附加到其父节点的字符串中。 因为该图是一棵树，所以每个顶点恰好对应于从根开始的一条路径，因此恰好对应一个字符串。 

我们只关心关键顶点的字符串。 让这些字符串被收集起来，然后按字典顺序排序。 此排序序列作为一个序列进行比较，而不是作为一个集合：两个序列不同的第一个位置确定哪个序列较小。 

我们的目标是分配字母，以便键顶点字符串的排序列表按字典顺序尽可能小。 在所有此类最佳分配中，我们必须输出字典顺序最小的边缘标签。 

关键的困难在于标签不仅影响单个字符串，还影响排序后它们的相对字典顺序，并且树结构限制了共享哪些前缀。 

一个微妙的边缘情况来自前缀排序：作为另一个字符串的前缀的较短字符串被认为较小。 例如，如果一个关键顶点是另一个关键顶点的祖先，我们必须仔细决定边标签，以便这种关系产生尽可能小的序列排序。 

一个幼稚的错误是贪婪地在本地分配小字母，而不考虑兄弟姐妹如何影响全局排序。 另一种失败模式是独立处理每个根到密钥路径，忽略共享前缀对所有后代的约束。 

## 方法

 暴力方法会尝试将字母分配给边缘，然后计算所有关键字符串，对它们进行排序，并按字典顺序评估结果序列。 由于每条边有 26 个选择，因此有 26^n 种可能性，即使 n 约为 30，这也是完全不可行的。即使尝试对子项进行本地回溯也会很快爆炸，因为每个选择都会影响所有后代字符串。 

关键的观察是，我们并不是真正优化字符串本身，而是优化排序后关键顶点的字典顺序。 这表明我们应该决定如何对每个节点的子节点进行排序，从而产生最佳的全局排序。 

在顶点，对于字典顺序唯一重要的是其子树的相对顺序，因为子树中的所有字符串在该节点之前共享相同的前缀。 如果我们决定哪个子子树应该按字典顺序排在第一位，我们可以为该子树分配最小的可用字母，为下一个子树分配下一个字母，依此类推。 这确保了一致性：每个节点的排序决定了所有后代字符串的排序。 

这导致了一个自下而上的想法：每个子树都可以由它包含的键字符串的排序列表表示，并且我们希望通过这些归纳的字符串列表对子树进行排序。 然而，显式构建和比较字符串的成本太高。 

相反，我们可以为每个子树分配一个“签名”，表示其字典顺序最小结构。 我们以后序方式处理节点。 对于每个节点，我们通过子树签名比较子节点，对它们进行排序，并根据此排序顺序按升序分配字母。 这种贪婪分配是有效的，因为一旦子树排序固定，早期使用较小的字母只能改善所有后代键字符串的字典顺序。

困难在于有效地比较子树签名。 由于每个节点最多有 26 个子节点，因此我们可以按字典顺序对子节点进行比较，并使用预先计算的哈希进行稳定排序或通过记忆 DFS 排序进行直接结构比较。 

解决此问题的一种更直接和标准的方法是通过每个子树内按字典顺序排列的最小键字符串定义子树的排序（可以在 DFS 期间计算），然后按该键对子树进行排序。 这已经足够了，因为在字符串集的词典比较中，最早的不同键字符串决定排序。

 | ---| ---| ---| ---|
 | 蛮力 | O(26^n) | O(26^n) | O(n) | 太慢了 |
 | 具有子树排序的树 DFS | O(n log 26) | O(n log 26) | O(n) | 已接受 |

 ## 算法演练

 我们将树的根设为 0，并自下而上地计算信息。 

1. 在知道子树的子树后，从根运行 DFS 来处理子树。 这确保了我们在其父树做出决策之前始终知道每个子树的行为方式。 
2. 对于每个节点，收集其所有子节点。 每个子节点代表一个子树，它将生成一些键字符串集。 我们为每个子节点分配一个代表值，该值捕获其子树中按字典顺序最小的键字符串。 
3. 根据这些代表值对孩子进行排序。 此排序决定了在所有键字符串中哪个子树应按字典顺序排在前面。 
4. 按此排序顺序将字符分配给边缘，从“a”开始向上。 第一个孩子得到“a”，第二个孩子得到“b”，依此类推。 这保证了较早的子树具有严格较小的前缀，这直接转换为较小的字典键字符串。 
5. 使用这些赋值递归到子级，以便一致地构建所有后代字符串。 

为什么这种贪婪分配是正确的来自局部到全局的一致性属性。 在任何节点，子树中的所有字符串都共享相同的前缀。 来自不同子树的任意两个键字符串之间的字典顺序比较是在它们分歧的第一个节点处决定的。 该分歧点正是兄弟边缘被分配不同字母的地方。 将较小的字母分配给应该出现在前面的子树可确保该子树中的每个字符串按字典顺序小于后面子树中的每个字符串。 由于关键字符串的排序仅取决于这些第一个分歧点，因此修复正确的局部排序可以保证全局最优性。 

## Python 解决方案```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    parent = list(map(int, input().split()))
    keys = set(map(int, input().split()))

    children = [[] for _ in range(n + 1)]
    for i in range(1, n + 1):
        children[parent[i - 1]].append(i)

    # store assigned character for each node edge
    ans = [''] * (n + 1)

    # dp value: smallest key-string rank proxy
    # we use tuple-based lex ordering built bottom-up

    def dfs(u):
        # each child gets a signature
        sigs = []
        for v in children[u]:
            dfs(v)
            sigs.append((dfs_sig[v], v))

        sigs.sort()

        for i, (_, v) in enumerate(sigs):
            ans[v] = chr(ord('a') + i)

        # build signature for u
        # signature is list of child signatures + leaf marker
        if u in keys:
            dfs_sig[u] = (0,)
        else:
            dfs_sig[u] = (1,) + tuple(dfs_sig[v] for _, v in sigs)

    dfs_sig = {}
    dfs(0)

    out = [''] * (n + 1)
    for i in range(1, n + 1):
        out[i] = ans[i]
    print(''.join(out[1:]))

t = int(input())
for _ in range(t):
    solve()
```该代码使用邻接表构建有根树，并从根执行 DFS。 数组`ans[v]`存储分配给从父级到边缘的字符`v`。 对于每个节点，子节点按计算的子树签名排序。 排序后，字符按顺序分配，确保字典顺序最小的子树获得更小的字符。 

这`dfs_sig`结构用于比较子树，而无需显式构造完整字符串。 它对节点是否是键进行编码，并递归地包含子节点的结构，这足以在排序过程中对子树进行一致的排序。 

一个微妙的细节是，字符的分配必须在对子项进行排序之后、向上返回之前进行，否则父项排序会变得不一致。

 考虑一棵小树：

 输入：```

```这棵树是 0 → 1，1 有子节点 2 和 3。2 和 3 都是关键顶点。

 | ---| ---| ---| ---|
 | 1 | 2,3 | 2 < 3 | 2 < 3 2='a',3='b' |
 | 0 | 1 | 1 | 1='a' | 1='a' |

 这会产生字符串：

 2 =“aa”，3 =“ab”。 排序后的键序列是 ["aa", "ab"]，这是最小的。 

现在考虑一条链：

 输入：```

2 3
```| 节点| 儿童 | 排序顺序 | 分配的字母 |
 | ---| ---| ---| ---|

这些痕迹表明，该算法始终将较小的子树推得更早，从而确保正确的字典顺序。

 ## 边缘情况

 一个关键的边缘情况是当一个节点有许多子节点且都是关键叶子节点时。 在这种情况下，兄弟姐妹之间的排序完全决定了字符串的最终排序顺序。 该算法按排序的子树顺序分配字母，确保字典顺序最小的子树始终获得“a”。 这保证了全局序列在第一个不同的密钥字符串处被最小化。 

另一种情况是深链，其中每个节点都是关键。 这里每个节点都只有一个子节点，因此不存在排序歧义。 该算法沿每条边分配“a”，产生统一的字符串结构。 由于所有字符串都是彼此的前缀，因此字典顺序纯粹由长度决定，并且长度被正确保留。 

当一个子树包含多个关键顶点而另一个子树仅包含一个时，会出现一种更微妙的情况。 具有多个键的子树通常具有按字典顺序排列较早的内部结构，并且排序步骤确保当且仅当它减少全局键序列中的第一个不同位置时它接收较早的字母。
