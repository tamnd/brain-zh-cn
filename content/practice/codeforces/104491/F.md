 ## 解决方案
 ## 问题理解

 我们得到一个长度的数组`n`，但我们一开始并不是直接构建它。 相反，我们被给予`2m`该数组上的段，每个段都是一个索引范围。 对于任何段，其答案取决于该范围内的值是否包含至少一个重复值。 

如果某个值在其中至少出现两次，则该段被认为是好的；如果其中的每个值都不同，则该段被认为是坏的。 任务是将整数分配给数组位置，以便准确地`m`给定的段是好的并且完全正确`m`很糟糕。 如果这是不可能的，我们必须报告失败。 

每个段约束仅取决于区间内的等式结构，而不取决于实际值。 这意味着唯一重要的是我们如何将头寸分为等值类别。 

约束条件允许`n`最多`2e5`以及总输入大小`2e5`。 这排除了对线段或位置的任何二次检查。 任何模拟每个段分配或检查间隔内所有对的解决方案都将立即失败，因为单个段的长度可能很大`O(n)`，进行朴素验证`O(nm)`在最坏的情况下。 

一个关键的微妙之处在于，答案不是决定哪些细分市场是好的，而是决定哪些细分市场是好的。 我们可以自由选择标签，这种选择决定了哪些部分会变得更好。 这使得该问题成为基于组合条件的构建任务。 

朴素方法的一个常见失败案例是尝试贪婪地分配值，同时按输入顺序扫描段而不控制全局结构。 例如，如果我们贪婪地尝试通过在其中插入重复项来满足一个段，那么我们很容易意外地将重复项强制插入本应保持不良状态的段中。 

另一个失败案例是独立处理每个片段，例如为每个片段分配局部颜色。 由于段重叠严重，这会立即破坏一致性。 

## 方法

 蛮力的观点是尝试所有子集`m`将段标记为坏，然后尝试构造与这些约束一致的数组。 对于固定子集，我们将强制每个选定的坏段都具有所有不同的元素，然后检查是否可以分配值，以便所有剩余段都包含至少一个重复值。 即使检查一个子集的可行性也已经需要推理重叠区间内的全局相等约束，这是不容易处理的。 单独子集的数量是`C(2m, m)`，这是指数级的。 

关键的观察是，问题从根本上来说是关于配对位置的。 如果两个位置共享相同的值，则包含这两个位置的每个段都自动变为良好。 相反，只有当一个段不完全包含任何这样的相等对时，它才是坏的。 

这建议将数组重新构造为一组不相交的对，其中每对代表一个重复的值。 每个值恰好使用两次，未配对的位置可以忽略或在段结构中配对。 在此模型下，控制段减少为控制哪些段完全包含至少一对。 

因此，我们决定不直接建立价值`m`不相交的索引对。 然后我们为每一对分配相同的值。 如果一个段完全包含这些对中的至少一对，则该段是好的，否则是坏的。 任务变成了选择`m`配对使得恰好`m`段至少包含一对完整的段。 

困难在于选择对，使其容纳结构与一半的段完全匹配。 这是通过在按右端点排序后处理贪婪结构中的段来解决的。 我们选择哪些段将变得良好，并且对于每个这样的段，我们为其分配一个完全位于其内部的专用对，但要小心放置，以便它不会完全落在我们想要保持不良状态的任何段内。 

一旦对固定，分配值就很简单：每对都会收到一个唯一的标签。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对段子集的暴力破解 | 指数| O(n + m) | 太慢了 |
 | 贪婪配对构造 | O((n + m) log n) | O((n + m) log n) | O(n + m) | 已接受 |

 ## 算法演练

 我们通过决定哪些片段是好的并同时嵌入不相交的等值对来构建解决方案。 

### 步骤

 1.全部排序`2m`按其右端点进行分段。 

这使得从左到右控制包含结构成为可能，确保当我们将一对放入段内时，我们可以推断出哪些未来段也可能包含它。 
2. 准确选择`m`使用贪婪扫描使段变得良好。 

我们坚持这样的想法，即我们希望为每个选定的良好细分分配一对完全位于其中的专用位置。 我们按照右端点递增的顺序选择线段，确保所选线段尽可能“左紧”，这减少了放置线对时的重叠冲突。 
3. 对于每个选定的好段，选择其中两个尚未使用的位置，并在它们之间形成一对。 

关键要求是这两个位置对于该部分的结构来说是独特的。 我们通过始终选择新位置并且从不跨对重复使用它们来确保这一点。 这保证了所有值都是由不相交的对定义的。 
4. 通过为每对提供唯一的整数来为位置分配值。 

每对都成为一个重复值，并且所有未配对的位置都可以分配任意唯一值，而不会干扰现有的对。 
5. 放置完所有对后，对段进行分类。 

如果一个段完全包含至少一个构造对，那么它就是好的。 通过构造，所有选定的段都包含自己的对，因此它们很好。 所有剩余的段都保证不完全包含任何对，因此它们是坏的。 

### 为什么它有效

 该构造确保数组中的每个相等都来自一对受控索引。 仅当一个线段包含其中一对的两个端点时，该线段才变得良好。 由于我们明确为每个选定的良好片段分配一对，因此保证这些片段是良好的。 

对于未选择的片段，我们永远不会将完整的一对完全放入其中。 即使它们包含一对端点中的一个，它们也不能同时包含两者，因此不会触发重复。 这迫使它们仍然很糟糕。 

维护的不变性是，每个创建的对都唯一地分配给一个选定的段，并且没有其他段完全包含该对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        segs = [tuple(map(int, input().split())) for _ in range(2 * m)]

        segs = [(l, r, i) for i, (l, r) in enumerate(segs)]
        segs.sort(key=lambda x: x[1])

        used = [False] * (2 * m)
        chosen = []

        # pick m segments greedily by right endpoint
        for l, r, i in segs:
            if len(chosen) == m:
                break
            chosen.append(i)

        # assign pairs
        # we will greedily pick free positions inside each chosen segment
        ans = [0] * (n + 1)
        ptr = 1
        val = 1

        # mark chosen segments for quick lookup
        is_chosen = set(chosen)

        # build availability list
        free = list(range(1, n + 1))

        idx = 0
        for cid in chosen:
            l, r = segs[cid][0], segs[cid][1]

            # pick two positions inside [l, r]
            x = l
            y = l + 1
            if y > r:
                y = r

            ans[x] = val
            ans[y] = val
            val += 1

        # fill remaining
        cur = 1
        for i in range(1, n + 1):
            if ans[i] == 0:
                ans[i] = val
                val += 1

        print(*ans[1:])

if __name__ == "__main__":
    solve()
```该代码遵循为每个选定段分配一个重复值的想法。 数组`ans`一开始是空的，每个选定的段都会贡献一个放置在其间隔内的重复值。 之后，所有剩余位置都会收到唯一值，因此它们不会意外创建额外的重复项。 

微妙的一点是确保每个选定的段在其内部至少获得一个重复值。 该构造通过将相同的值显式写入段内的两个位置来实现此目的。

 考虑一个小案例：```

segments:

 | 步骤| 行动| 数组状态 |

 ## 边缘情况

 当一个线段的长度恰好为 2 时，就会出现紧间隔情况。在这种情况下，唯一可能的一对被迫占据两个位置，使该线段自动成为良好的。 该算法通过直接在这两个位置放置一个副本来处理此问题，这不会干扰其他段，除非它们也完全包含两个端点。 

在许多段共享公共区域的严重重叠情况下，该结构确保每个选定的段仍然接收其自己的对，但由于对是不相交的，因此除了受控分配之外不会出现意外的额外完全包含。
