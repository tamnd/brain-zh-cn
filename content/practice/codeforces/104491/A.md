 ## 解决方案
 ## 问题理解

 我们有一排从左到右索引的鸡。 每只鸡都有容量限制，这意味着它只能吃一定数量的谷物。 除此之外，还有几个喂食器，每个喂食器覆盖鸡的连续部分并包含固定数量的谷物。 

不同之处在于如何为每只鸡过滤喂食器。 对于固定的鸡肉指数$i$，我们只保留其细分市场包括的支线$i$。 所有其他馈线都被完全忽略。 剩下的喂食器中，我们考虑总共可以用多少粒，但每只鸡仍然不能超过自己的容量。 

所以对于每只鸡$i$，我们想象一个只有支线覆盖的世界$i$存在。 在那个世界中，我们希望这些喂食器提供的谷物总数，但受到每只鸡的容量限制。 

输出是一个列表$n$值，每只鸡一个，描述在该过滤规则下该鸡的可用谷物总量。 

这些限制足够严格，以至于对鸡和喂食器的二次方法会太慢。 和$n, m \le 10^5$每个测试用例和跨测试的总和，任何解决方案都必须接近线性或$O((n + m)\log n)$。 对所有喂食器进行简单的每只鸡扫描将执行最多$10^{10}$在最坏的情况下进行操作，这是不可行的。 

重叠行为产生了一个微妙的点。 一个喂食器可以饲养多只鸡，但对于每只鸡，我们独立决定是否将其包括在内。 这意味着支线的贡献是“局部全局”的：它仅取决于该指数是否位于其细分市场中。 

一个天真的错误是假设我们必须从头开始重新计算每只鸡的总和。 另一个错误是忘记了为一个索引排除的 feeder 可能仍包含在附近的索引中，因此我们无法全局预删除 feeder。 

## 方法

 暴力解决方案修复了一只鸡$i$，然后迭代所有 feeder 和 sum$c_j$对于那些间隔$[l_j, r_j]$包含$i$。 这是正确的，因为它直接遵循规则。 然而，每次查询的成本$O(m)$，并为所有人做这件事$n$鸡导致$O(nm)$，达到$10^{10}$最坏情况下的操作。 

关键的观察是对于固定的鸡$i$，馈线贡献当且仅当$l_j \le i \le r_j$。 我们可以将其重写为：所有活跃的馈线$i$正是那些区间覆盖的$i$。 因此，每个馈线将其权重贡献给一系列连续的指数，即从$l_j$到$r_j$。 这是经典的“范围添加，点查询”结构。 

而不是重新计算每个$i$，我们扭转视角。 每个供料器添加$c_j$到其区间内的每个索引。 因此我们要计算，对于每个位置$i$，所有的总和$c_j$超过覆盖它的喂食器。 这就变成了差分数组或前缀和累加问题。 

一旦我们计算出总覆盖率总和的基本数组，我们就必须尊重鸡的容量。 每只鸡不能吃超过$a_i$，所以最终的答案很简单$\min(a_i, \text{coverage}[i])$。 

这将问题转换为对差异数组的两次线性传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了 |
 | 最优（差异数组）| O(n + m) | O(n) | 已接受 |

 ## 算法演练

 如果我们将所有喂料器应用为范围添加，然后按容量进行限制，我们会计算每个位置有多少谷物可用。 

1.初始化一个数组`diff`尺寸的$n+2$带零。 该数组将以压缩形式存储范围更新。 我们的想法是，我们不是更新范围内的每个位置，而是标记贡献的开始和结束位置。 
2. 对于每个馈线$(l_j, r_j, c_j)$， 添加$c_j$在`diff[l_j]`并减去$c_j$在`diff[r_j + 1]`。 这编码了贡献仅在以下时间之间有效$l_j$和$r_j$。 减法可确保效果在范围结束后停止。 
3. 构建前缀和`diff`恢复实际的覆盖范围数组`cover[i]`。 在每个索引处$i$,`cover[i]`等于此时所有活跃馈线贡献的总和。 这是有效的，因为每个范围更新在开始时贡献一个 +c，在结束后贡献一个 -c，因此前缀累积会重建正确的重叠和。 
4. 每只鸡$i$，计算最终答案为$\min(a_i, cover[i])$。 这强制了每只鸡的容量限制。 
5. 输出测试用例的所有答案。 

### 为什么它有效

 每个馈线贡献$c_j$精确到其区间内的索引。 差异数组确保在前缀求和期间每个此类间隔都被精确计数一次。 不会丢失或重复计算任何贡献，因为在间隔结束后每次添加都会有匹配的取消。 位置处的结果前缀和$i$等于覆盖的所有馈线的总和$i$，这正是应用容量限制之前所需的数量。 由于每个索引的容量是独立的，因此夹紧不会干扰其他位置的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        diff = [0] * (n + 2)

        for _ in range(m):
            l, r, c = map(int, input().split())
            diff[l] += c
            diff[r + 1] -= c

        cur = 0
        res = [0] * n

        for i in range(1, n + 1):
            cur += diff[i]
            res[i - 1] = min(a[i - 1], cur)

        print(*res)

if __name__ == "__main__":
    solve()
```该实现完全反映了算法。 这`diff`数组大小已确定$n+2$以安全地处理$r+1$更新无边界检查。 前缀累加变量`cur`避免重复重新计算前缀和。 每个位置都处理一次，确保每个测试用例的线性性能。 

一个常见的陷阱是忘记索引在输入中是从 1 开始的，但在 Python 数组中是从 0 开始的。 该解决方案仅在写入时始终发生变化`res`, 保持`diff`为了清晰起见，与基于 1 的逻辑对齐。

 喂料器 1 为 1 至 2 号鸡喂 3 粒谷物，喂料器 2 为 2 至 3 号鸡喂 2 粒谷物。 容量为$a = [2, 5, 2]$。 

我们一步一步构建差异数组。

 ## 边缘情况

 具有单个喂食器的最小单鸡案例测试 r+1 减法是否打破数组边界。 用于输入$n=1$,$l=r=1$，更新写入`diff[2]`，这是有效的，因为数组的大小是固定的$n+2$。 前缀和产生正确的覆盖范围，钳位确保最终值等于$\min(a_1, c_1)$。 

没有馈线的情况确保前缀总和在任何地方都保持为零。 无论容量如何，该算法都会正确输出零，因为没有激活范围更新。 

一组完全重叠的馈线测试累积的正确性。 每个索引接收所有馈线值的总和，最后的最小操作确保即使非常大的重叠也会被每个位置独立地限制，从而确认保留每个索引的独立性。
