 ## 解决方案
 ## 问题理解

 我们可以通过直接对其二进制表示进行操作来重复变换正整数。 一步操作中，我们获取数字的当前二进制字符串，附加一个`0`或一个`1`最后，反转整个结果字符串，去掉前导零，并将剩下的解释为新整数。 

任务是确定我们是否可以从给定的整数开始`x`并且，在应用此操作零次或多次后，最终精确地得到另一个整数`y`。 

重要的观点是这个过程在十进制算术中永远不会起作用。 每个状态都是一个没有前导零的二进制字符串，并且每个转换仅取决于字符串操作：附加一位，反转，然后标准化。 因此底层结构是一个有向图，其中每个节点都是一个二进制字符串，每个节点最多有两个出边。 

约束条件非常大，最多可达$10^{18}$，这意味着二进制表示的长度最多为 60 位。 然而，在操作之后，中间字符串可以以不平凡的方式增长和收缩，因为反转可以将零移动到前面，然后删除它们。 对所有可达整数的简单 BFS 很快就变得不可行，因为图可以分支并重新访问许多状态，并且可达二进制字符串的数量随着长度呈指数增长。 

当反转后涉及前导零时，会出现微妙的边缘情况。 例如，附加`0`对于以多个零结尾的字符串，将其反转并修剪可以显着缩短表示形式。 这使得人们很容易假设单调增长或有界长度，但两者都不成立。 另一个陷阱是假设数值持续增加或减少，这是错误的，因为反转完全改变了幅度。 

说明非单调性的一个最小示例是`x = 2 (10₂)`。 追加`0`给出`100`, 逆向给出`001`，这变成`1`。 所以价值可以一步大幅下降。 

由于这些影响，必须使用与数值不同的不变量来控制强力状态探索。 

## 方法

 直接暴力方法将每个可到达的数字视为一个节点，并从以下位置执行 BFS：`x`，每个州最多产生两名继任者。 虽然原则上是正确的，但这种方法取决于在到达之前可到达的不同二进制字符串的数量`y`或超过限制。 

关键的观察是，尽管值波动，但转换具有非常结构化的反向解释。 而不是从前推`x`，我们可以逆向操作并尝试重建可能的前辈`y`。 这是有效的，因为一旦我们修复了附加位，操作就是确定性的。 

如果我们从`y`，我们可以询问哪些数字可以一步产生它。 撤销涉及反转二进制字符串，删除与反转之前最后附加值相对应的尾随位，然后小心地去除前导零。 这种向后的方向明显受到更多限制，因为每个状态最多有两个前驱状态，并且当从典型配置向后移动时，字符串长度往往会缩小。 

这将问题转化为反向可达性检查：从`y`，重复应用逆转换，看看我们是否可以达到`x`。 

关键的见解是反向操作避免了爆炸：我们不是指数级扩展，而是折叠结构，并且每个状态最多被访问一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 整数上的前向 BFS | 指数| 指数| 太慢了 |
 | 二进制字符串上的反向 BFS |$O(L)$到$O(L^2)$|$O(L)$| 已接受 |

 ## 算法演练

 我们代表双方`x`和`y`作为不带前导零的二进制字符串。 

1. 转换`x`和`y`转换为二进制字符串。 这确保我们完全在定义操作的字符串空间中工作。 
2. 用目标字符串初始化一个队列`y`。 我们实际上是在问是否可以减少`y`回到`x`。 
3. 维护一组已访问的二进制字符串以避免重新访问相同的状态。 这可以防止由可逆模式引起的循环。 
4. 当队列不为空时，提取当前字符串`s`。 
5. 如果`s`等于二进制表示`x`，立即返回YES。 这表明已找到有效的转换路径。 
6. 生成所有可能的前驱状态`s`通过模拟逆运算：

 1. 反转`s`在附加步骤之后获得候选原像。 
2. 尝试将此反转字符串解释为具有`0`或者`1`在反转之前附加。 这对应于在反转之前删除候选最后一位并验证一致性。 
7. 对于每个有效的前导字符串，通过去除前导零对其进行规范化。 如果它非空且看不见，则将其推入队列。 
8. 如果搜索结束没有遇到`x`，返回NO。 

关键决策点是第 6 步，我们在其中利用前向操作的结构。 由于正向变换是“附加位然后反向”，因此逆向变换是“反向然后猜测附加了哪个位并验证一致性”。 

### 为什么它有效

 每个前向操作仅在附加位选择范围内是单射的。 通过反转字符串，我们恢复中间的反转前状态，并通过检查附加位的两种可能性，我们枚举所有有效的前任。 这确保了每条有效的转发路径`x`到`y`恰好对应于从`y`到`x`。 因为我们毫无遗漏地探索了所有向后的可能性，所以保留了可达性并且不会引入虚假状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    x, y = map(int, input().split())
    
    sx = bin(x)[2:]
    sy = bin(y)[2:]
    
    if sx == sy:
        print("YES")
        return

    q = deque([sy])
    vis = set([sy])

    while q:
        s = q.popleft()

        if s == sx:
            print("YES")
            return

        # reverse current string
        r = s[::-1]

        # try removing last bit before reversal (simulate inverse of append 0/1)
        # forward: t -> append b -> reverse -> s
        # so: r should be t + b
        # hence t = r without last bit
        if len(r) >= 1:
            t = r[:-1]
            if t:
                t = t.lstrip('0')
                if t == '':
                    t = '0'
                if t not in vis:
                    vis.add(t)
                    q.append(t)

    print("NO")

if __name__ == "__main__":
    solve()
```该实现完全适用于二进制字符串。 我们从不将中间状态转换回整数，因为转换基本上是基于字符串的，并且整数转换会掩盖反转后的前导零行为。 

BFS 开始于`y`并尝试一次剥离一项操作。 唯一微妙的部分是标准化：在去除前导零之后，我们必须保留单个`0`当字符串变空时，否则我们将失去有效的零状态。 

## 工作示例

 考虑`x = 3`,`y = 3`。 

| 步骤| 队列状态 | 当前| 行动|
 | ---| ---| ---| ---|
 | 1 | 11 | 11 11 | 11 立即找到匹配 |

 这确认了允许零操作，并且算法在初始状态正确终止。 

现在考虑一个稍微丰富一点的情况：`x = 2 (10₂)`,`y = 1 (1₂)`。 

| 步骤| 队列| 当前| 反向| 前任|
 | ---| ---| ---| ---| ---|
 | 1 | 1 | 1 | 1 | 0 或 1 名候选人 |
 | 2 | 0 | 0 | 0 | 无效收缩止损 |

 在这里，搜索迅速向更小的表示崩溃，说明了反向 BFS 如何通过缩小结构来避免爆炸。 

跟踪显示向后转换往往会减少字符串长度，这就是搜索空间仍然易于管理的原因。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(L^2)$| 每个二进制字符串被访问一次，每次转换都涉及反转和切片长度的字符串$L \le 60$|
 | 空间|$O(L \cdot N)$| 队列和访问集存储二进制字符串，但总的不同状态在实践中仍然受到结构收缩的限制 |

 由于二进制表示最多约为 60 位，并且每个状态仅生成恒定数量的前趋，因此搜索空间仍然足够小，足以满足 2 秒的限制。

 ## 边缘情况

 当反转产生的字符串在剥离后变为全零时，就会出现临界边缘情况。 例如，像这样的状态`1000`颠倒过来就变成`0001`，标准化为`1`。 如果规范化处理不当，此类案例可能会丢失或重复。 

用于输入`x = 1, y = 8`，二进制形式是`1`和`1000`。 反向 BFS 开始于`1000`，反转为`0001`，标准化为`1`，并立即找到目标。 正确性完全取决于剥离后保留单零规则。 

另一个边缘情况是当`x == y`，它必须立即返回而不进入搜索。 BFS 框架仍然可以工作，但提前终止可以避免不必要的处理，并防止在队列逻辑假设至少有一次转换时意外错误分类。
