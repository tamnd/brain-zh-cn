 ## 解决方案
 ## 问题理解

 我们得到了一组整数。 我们重复地精确删除两个元素$k$次，每次移除都会产生一个值，该值会添加到运行分数中。 在这些之后$k$操作中，剩下的任何元素也会直接添加到分数中。 

操作本身是不对称的：如果我们选择值$x$和$y$，贡献是$\left\lfloor \frac{x}{y} \right\rfloor$。 由于顺序很重要，因此选择哪个数字成为分子、哪个数字成为分母会直接影响结果。 删除两个元素后，它们将永久消失，因此每个元素都只使用一次，无论是成对还是作为剩余元素。 

约束条件$2k \le n \le 100$意味着我们总是最多配对数组的一半，并且元素总数足够小，以至于每个测试用例都可以接受二次甚至三次推理。 然而，测试用例的数量最多可达 500 个，因此任何对配对的指数搜索都是不可行的。 

核心困难在于配对选择在全球范围内相互作用：尽早选择分母会改变未来操作中剩余的内容，也会改变哪些元素最终不配对，从而直接添加到答案中。 

一些微妙的边缘情况很重要。 

如果所有数字都相等，则每个楼层划分都是 1，因此每个配对都贡献恰好 1。任何试图“优化”配对顺序但意外地将剩余部分错误配对的不正确的贪婪策略仍然会产生固定的总数，从而使调试变得困难，因为所有策略看起来都是相同的。 

如果数组包含许多 1，那么使用 1 作为分子总是安全的，因为当与更大的值配对时它会产生 0，而使用它作为分母则是灾难性的，因为它会产生很大的值。 对相邻元素进行排序和配对的天真贪婪很容易放错 1 并增加分数。 

如果有零（不是这个问题，因为$a_i \ge 1$），除法不对称性将是极端的； 这强化了分母选择是主要杠杆。 

## 方法

 暴力方法会尝试模拟所有可能的操作序列。 在每一步中，选择任何无序的剩余索引对并决定方向。 后$k$步骤，计算剩余总和。 状态空间缩小为$n, n-2, n-4, \dots$，但分支因子大致为$O(n^2)$一开始，导致周围爆炸$\binom{n}{2k}$对结构乘以方向选择。 即使是为了$n = 100, k = 50$，这是完全不可行的。 

关键的结构见解是最终答案分解为两个独立的部分：对的贡献和剩余元素的贡献。 一旦我们决定哪些元素保持不配对，剩下的部分就很简单，所以真正的问题是决定哪些元素$2k$元素是配对的以及它们如何定向。 

现在观察楼层划分的行为。 对于任意固定对$x, y$，贡献很小，除非$x \gg y$。 由于我们想要最小化分数，因此我们希望避免大数成为分子超过小分母的情况。 这表明了一种贪婪的结构：应该保护大数不成为除法中的分子，而小数是成为分子的最佳候选者。 

这导致了一个标准的配对策略：对数组进行排序。 然后将最小元素视为潜在分子，将最大元素视为潜在分母。 每个运算应该将一个小数与一个大数配对，使用小数作为分子，大数作为分母，因为这样可以最小化$\left\lfloor \frac{x}{y} \right\rfloor$。 

剩余元素应该是排序数组的中间部分，因为在剩余位置使用极值会增加总和。 因此，我们为分母保留最大的可能元素，为分子保留最小的元素，在需要时保留中间的不成对元素。 

这种贪婪是最优的，因为这种结构的任何反转都可以证明会微弱地增加分数：将小分子与较大分子交换不能减少除法结果，而交换分母只会增加大分子与较小分母的接触。

 ## 算法演练

 1. 对数组进行非降序排序。 排序公开了决定哪些值应用作分子和分母所需的全局结构。 
2. 将流程拆分为选择$k$配对并离开$n - 2k$元素未配对。 未配对的元素将被视为排序数组的中间部分，因为极值在控制除法结果方面更有用。 
3. 使用两个指针：一个从左侧开始（小值），另一个从右侧开始（大值）。 将最小的可用元素与最大的可用元素配对。 
4. 对于每一对，计算$\left\lfloor \frac{a[l]}{a[r]} \right\rfloor$并将其添加到乐谱中，然后移动$l$向前和$r$落后。 这可以确保分子保持较小，分母保持较大，从而最大限度地减少贡献。 
5. 继续直到完全$k$形成对，消耗$2k$元素。 
6. 将所有剩余的未配对元素添加到分数中。 这些已经是删除后排序数组的中间部分$k$最小的和$k$最大的元素。 

### 为什么它有效

 不变的是，在每个配对步骤中，我们都保持小值和大值之间尽可能最强的分离。 当前最小与当前最大配对的任何偏差只能替换一对$(x, y)$与任一$(x, y')$在哪里$y' \le y$，增加商，或者$(x', y)$在哪里$x' \ge x$，也增加了商。 因此，相对于替代匹配，贪婪配对永远不会增加任何单独的操作成本，并且通过排除极端情况来最小化剩余总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        l, r = 0, n - 1
        ans = 0

        # take k pairs: smallest with largest
        for _ in range(k):
            ans += a[l] // a[r]
            l += 1
            r -= 1

        # remaining elements are unpaired
        for i in range(l, r + 1):
            ans += a[i]

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先进行排序，以便配对决策成为位置决策而不是组合决策。 两指针循环显式消耗$k$最小的和$k$最大的元素。 剩余的段是连续的，因此求和很简单。 

一个微妙的点是，我们从不重新考虑配对方向：我们总是将最小的作为分子，最大的作为分母。 任何反转只会增加商，因为翻转整数除法是高度不对称的。 

剩下的循环使用包含边界，因为之后$k$精确地从两端移除$n - 2k$元素保留在中间。

 ## 边缘情况

 关键的边缘情况是所有元素都相等。 例如，$n=4, k=2$和$[7,7,7,7]$。 算法对$(7,7)$两次，产生贡献$1 + 1 = 2$，不留余数。 任何改变配对顺序的错误策略仍然会产生相同的结果，这可能会隐藏更一般情况下的错误。 

另一种情况是小元素与大元素相比非常小，例如$[1,1,1,100,100,100]$和$k=2$。 该算法确保所有 1 用作分子，大数用作分母，保证所有除法贡献为零，而任何使大数成为分子的交换都会立即增加分数。 

最后一个微妙的情况是$k=0$，其中不允许配对。 正确的行为是直接返回所有元素的总和。 该算法自然会处理这个问题，因为跳过了配对循环，并将整个数组求和为剩余数组。
