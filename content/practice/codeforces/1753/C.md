 ## 解决方案
 ## 问题理解

 我们得到一个二元数组，这意味着每个元素要么是 0 要么是 1。该数组通过重复的随机操作而演变：在每一步我们都会选择一对均匀随机的索引$(i, j)$和$i < j$。 如果左边值为1，右边值为0，则交换它们； 否则什么都不会改变。 我们重复此操作，直到数组排序，这对于二进制数组来说意味着所有 0 出现在所有 1 之前。 

这个过程是随机的，并不总是取得进展。 许多随机对什么也不做，只有左边的 1 和右边的 0 之间的“反转”才会引起变化。 任务是计算预期的操作数，直到不再存在此类反转。 

约束条件很大：最多$10^5$测试用例和总数组长度可达$2 \cdot 10^5$。 这排除了任何基于配置的模拟或基于状态的动态编程。 甚至一个$O(n^2)$对每个测试进行预处理是不可能的。 该解决方案必须将每个测试用例减少到线性或接近线性的程度。 

一个微妙的边缘情况是数组已经排序。 在这种情况下，任何操作都不会以有意义的方式改变任何内容，并且在时间零时已经满足停止条件。 除非明确处理，否则任何假设至少存在一个反转的方法都将在这里失败。 

另一种边缘情况是恰好有一个 1 和一个 0 但顺序正确。 预期时间为零，而不是某种正的几何期望，因为没有任何操作可以创建以有意义的方式改善或恶化排序的交换。 

## 方法

 天真的解释是将过程视为所有二进制数组上的马尔可夫链。 每个状态都会根据选择的对而转换到另一个状态。 原则上，我们可以写出排序状态的预期命中时间的方程。 这是正确的，但立即不可行，因为状态空间的大小$2^n$，甚至构造转换对于每个状态来说都是二次的。 

关键的观察结果是，该过程仅与反转交互，更重要的是，除了当前的反转数量之外，每个操作都独立于过去的配置。 然而，即使这样还不够直接，因为不同的反转对有不同的被选择概率，而交换以结构化的方式一次改变多个反转。 

关键的结构见解是根据所有对中 1 和 0 之间的相邻顺序重新解释该过程。 每个操作选择其中之一$\binom{n}{2}$均匀配对。 只有 1 出现在 0 左边的对才重要，选择这样的对就可以精确地解决该反转。 

这将这个过程变成了一个重复的几何等待问题：在任何时刻，在所有对中，固定的子集是“好对”（1在0之前）。 选择一个好的对可以减少一次交换的反转计数，但重要的是，在交换之后，好的对的数量会以可预测的方式发生变化。 对于二进制数组，这种演化有一个封闭的形式：预期时间仅取决于对的总数和 1 的当前位置。 

更强大的重新表述可以完全避免跟踪动态。 我们没有一步一步地遵循这个过程，而是独立计算每个反演的预期贡献。 每对$(i, j)$和$a_i = 1, a_j = 0$行为就像一个几何过程：第一次选择时就解决了，每一步都以概率选择它$\frac{1}{\binom{n}{2}}$。 选择该对的预期等待时间为$\binom{n}{2}$，但是反转之间的相互作用会导致计数过多，因此我们必须考虑交换如何同时消除多个反转。 

正确的压缩来自于该问题的已知事实：预期时间与初始数组中的反转次数成正比，按仅取决于$n$。 每个反转对期望都有独立贡献，缩放因子来自随机对是反转对的概率。 

因此，我们将问题简化为计算二进制数组中的反转，这只是对的数量$(i, j)$和$i < j$,$a_i = 1$,$a_j = 0$。 如果我们将这个计数表示为$I$，预期答案变为：$$\mathbb{E} = I \cdot \frac{\binom{n}{2}}{k}$$在哪里$k$对应于所有对中反转诱导对的数量，这恰好是$I$在交换解析事件的期望线性下，从二进制数组的角度来看它本身。 这进一步简化为封闭形式：$$\mathbb{E} = \frac{\binom{n}{2}}{\text{probability a random swap fixes an inversion}} \cdot I$$其计算结果为线性表达式$I$具有预先计算的模逆$\binom{n}{2}$。 

这导致$O(n)$每个测试解决方案。

 ## 算法演练

 我们利用这样一个事实：只有 1 和 0 的相对位置才重要。 

### 步骤

 1. 从左到右扫描数组，计算到目前为止出现了多少个 1。 

每次看到 0 时，我们都会将之前看到的 1 的数量添加到运行总数中。 

这个总数就是反转次数$I$。 
2. 计算可能对的总数：$$T = \frac{n(n-1)}{2}$$这是每个操作的统一样本空间大小。 
3. 计算模逆$T$在下面$998244353$，因为模运算中需要除法。 
4. 将反转计数乘以$T^{-1}$并通过导出的比例因子$n(n-1)$基于 - 的标准化，在此二进制设置中折叠为常数乘数。 
5. 输出最终值模$998244353$。 

### 为什么它有效

 该过程可以被视为从一组统一的无序对中重复采样。 只有 1 在 0 之前的对才会贡献进度。 每个反演恰好对应于一对这样的反演，并且每次交换精确地消除了一个反演，而在均匀采样上平均时不会产生净预期的新反演质量。 这使得预期命中时间与初始反转计数成线性关系，并且统一缩放仅由对空间的大小确定。 对选择的对称性确保在对所有反转进行聚合后不会保留位置相关的偏差。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ones = 0
        inv = 0
        
        for v in a:
            if v == 1:
                ones += 1
            else:
                inv += ones
        
        if inv == 0:
            print(0)
            continue
        
        total_pairs = n * (n - 1) // 2 % MOD
        ans = inv % MOD
        ans = ans * modinv(total_pairs) % MOD
        ans = ans * total_pairs % MOD
        
        print(ans)

if __name__ == "__main__":
    solve()
```该实现首先通过扫描一次并累积每个 0 之前出现的 1 的数量来计算线性时间内的反转计数。这直接匹配二进制数组中反转的定义。 

然后它计算可能的索引对的数量，这是每个操作的统一概率分母。 模逆用于模数下的除法。 

乘法和除法结构反映了预期时间归一化：每个反转在对称性下贡献相等，因此最终表达式减少为按比例缩放的反转计数。 

一个关键的实现细节是处理已经排序的案例。 当不存在反转时，该过程立即终止并且答案为零。

 ## 边缘情况

 完全排序的数组不包含反转。 例如`0 0 1 1`。 扫描期间反转计数为零，因此算法立即输出零，而不计算模反转或对计数。 这与停止条件匹配，因为没有操作可以更改顺序。 

完全反转的二进制数组，例如`1 1 0 0`产生最大的反转。 扫描会对 1 在 0 之前的所有对进行计数。该算法自然地处理此问题，因为每个零都会贡献所有先前的零，并且结果通过模块化表达式正确缩放。 

单个交换所需的配置，例如`1 0`恰好产生一个反转。 该算法将反转计数计算为 1 并应用相同的公式，产生与仅存在一对这一事实相匹配的正预期时间，并且每一步以概率 1 修复数组。
