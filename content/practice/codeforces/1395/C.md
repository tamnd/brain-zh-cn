 ## 解决方案
 ## 问题理解

 我们有两个小整数数组。 对于第一个数组中的每个元素，我们必须从第二个数组中选择一个元素并使用按位 AND 将它们组合起来。 这会为第一个数组中的每个位置生成一个新值。 选择所有这些配对后，我们对所有结果值进行按位“或”运算，并希望最终的“或”值尽可能小。 

另一种看待它的方式是，第一个数组中的每个元素必须从第二个数组中“选择”一个伙伴，并且每个选择都会生成一个位掩码，该位掩码有助于全局位联合。 由于 OR 会永久累积位，因此任何选定的 AND 结果中出现的任何位都将出现在最终答案中。 目标是选择配对，以便尽可能少的位在这个联合体中存活。 

约束很小：两个数组的大小最多为 200，每个数字适合 9 位，这意味着所有值都在 0 到 511 的范围内。这种组合至关重要。 小的位宽使我们能够根据位的子集而不是数值大小进行思考，并且少量的元素允许对子集或状态进行动态编程。 

一种简单的方法是尝试将 n 个元素中的每一个独立地分配给 m 个选项之一。 这已经给出了 mⁿ 的可能性，即使对于中等的 n 也是完全不可行的。 即使尝试直接从组合中计算所有可能的 OR 结果也会爆炸。 

更微妙的失败案例来自于贪婪思维。 人们可能会尝试为每个 aᵢ 分配 bⱼ，从而在本地最小化 aᵢ 和 bⱼ。 这是行不通的，因为减少单个 cᵢ 并不能保证全局 OR 较小。 由于其他限制，早期引入一点可能是不可避免的。 

例如，如果一个 aᵢ 只能通过使用特定的 bⱼ 来避免一位，但另一个 aₖ 没有选择并且无论如何都会强制该位，那么对 aᵢ 的贪婪选择是无关紧要的。 所有分配之间的耦合是通过 OR 实现的全局耦合。 

## 方法

 强力解释是为每个 aᵢ 分配 m 个值之一并计算所得的 OR。 每个赋值都会产生 n 个值 cᵢ = aᵢ & bⱼ，然后我们对它们进行 OR 运算。 这需要探索 mⁿ 分配，甚至修剪也没有任何意义，因为 OR 不允许早期局部最优性保证。 当 n = 200 时，这远远超出了任何计算极限。 

关键的观察来自按位或的结构。 最终的答案是一个9位掩码。 这意味着最终结果只有 2⁹ = 512 种可能。 我们可以逆向思考，而不是直接决定分配：我们猜测最终的 OR 掩码并检查它是否可以实现。 

修复候选掩码 X。我们想知道是否可以分配每个 aᵢ a bⱼ，使得每个结果 (aᵢ & bⱼ) 都是 X 的子掩码。如果任何选定的对引入 X 之外的位，则该候选会立即失败。 因此，对于每个 aᵢ，我们只考虑 bⱼ 使得 (aᵢ & bⱼ) ⊆ X。 

现在问题变成：对于每一个aᵢ，是否存在至少一个与X兼容的bⱼ？ 如果所有 i 都为“是”，则 X 是可以实现的。 这样做的原因是我们只将最终的 OR 限制在 X 内。我们不关心区分使用了哪个 bⱼ，只关心每个 aᵢ 都有一个有效的选择。 

这将问题减少到检查 512 个候选者，每个候选者需要扫描 n·m 对。 这很容易足够快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分配| O(米ⁿ) | O(n) | 太慢了|
 | 尝试所有 OR 面罩 | O(2⁹·n·m) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们迭代从 0 到 511 的所有可能的位掩码 X，并测试 X 是否可以作为最终答案。

1. 从候选掩码 X 开始，并假设它是目标 OR 结果。 我们将此解释为一个约束，即 X 之外的任何位都不允许出现在任何 cᵢ 中。 
2. 对于每个元素 aᵢ，我们检查是否存在至少一个 bⱼ 使得 (aᵢ & bⱼ) 是 X 的子掩码。这确保将 aᵢ 分配给 bⱼ 不会引入禁止位。 
3. 如果对于某些 aᵢ 不存在这样的 bⱼ，则 X 是不可能的，因为在不违反约束的情况下无法对 aᵢ 进行赋值。 
4. 如果每个 aᵢ 至少有一个有效的 bⱼ，则 X 可行。 我们将答案更新为所有可行 X 的最小值。 

微妙之处在于，一旦 X 固定，可行性就与每个元素无关。 我们不是共同优化分配；而是共同优化分配。 我们只检查存在性。 OR 耦合消失了，因为它已经被编码到 X 中。 

### 为什么它有效

 对于固定掩码 X，任何有效的赋值都必须只产生 X 内部的位。如果即使一个 aᵢ 没有兼容的 bⱼ，那么该 aᵢ 的每个可能的赋值都会引入一个禁止位，因此 X 不能是最终的 OR。 

相反，如果每个 aᵢ 至少有一个兼容的选择，我们可以为每个索引独立分配，并且永远不会在 X 之外引入位。由于所有生成的掩码都是 X 的子集，它们的 OR 也是 X 的子集，这意味着最终的 OR 不能超过 X。因为我们只接受可以实现所有元素的掩码，所以 X 是可以实现的。 

因此，算法搜索最终 OR 的最小可实现上限。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    INF = 10**9
    ans = INF

    for mask in range(1 << 9):
        ok = True

        for i in range(n):
            found = False
            for j in range(m):
                if (a[i] & b[j]) | mask == mask:
                    found = True
                    break
            if not found:
                ok = False
                break

        if ok:
            ans = min(ans, mask)

    print(ans)

if __name__ == "__main__":
    solve()
```代码直接实现了对每个候选mask的可行性测试。 关键表达式`(a[i] & b[j]) | mask == mask`检查 AND 结果的所有位是否都包含在候选掩码中。 这相当于`(a[i] & b[j]) ⊆ mask`。 

嵌套循环是可以接受的，因为 n 和 m 最多为 200，并且外部掩码循环只有 512 次迭代。 

一个微妙的实现细节是早期破坏：一旦我们找到 aᵢ 的有效 bⱼ，我们就停止检查进一步的 j 值。 同样，一旦任何 aᵢ 失败，我们就完全停止检查掩码。 这可以防止不必要的工作。

 ## 边缘情况

 一种边缘情况是所有 aᵢ 都为零。 任何 bⱼ 在 AND 之后都会产生零，因此每个掩码都是可行的，并且最小值为零。 该算法处理此问题是因为对于 mask = 0，每对都会生成 0，它是 0 的子掩码，因此可行性立即成立。 

另一个边缘情况是当某些 aᵢ 对于小掩码没有兼容的 bⱼ 时。 例如，如果 aᵢ 具有无法通过与 bⱼ 进行任何 AND 消除的高位，则排除该位的所有掩码都将在该索引处失败。 该算法在该掩码的可行性检查步骤中准确地检测到这一点。 

最后一种情况是不同的 aᵢ 需要不兼容的 bⱼ 选择。 该算法不会尝试同步选择； 相反，它仅检查固定掩码下每个元素的存在性，从而在修复 OR 边界后正确捕获该独立性。
