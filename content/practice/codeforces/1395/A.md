 ## 解决方案
 ## 问题理解

 我们得到了四种球的计数：红、绿、蓝和白。 唯一允许的操作是将一个红球、一个绿球和一个蓝球转换为白球。 我们可以多次应用此操作。 

执行这些转换后，我们必须决定是否可以将所有剩余的球排列成回文序列。 

回文排列仅取决于每种颜色的计数，而不取决于它们的身份或超出对称性的顺序限制。 真正的困难在于，该操作让我们将三个颜色组中的每一个单位交易为白色，这以耦合的方式改变了系统的奇偶校验结构。 

每个测试用例的约束都很小，最多 100 个用例，值大到 10^9。 这立即排除了任何对操作的模拟或任何状态搜索。 唯一可行的方法是推理不变量和奇偶校验，因为该操作保留了计数的某些模块化属性。 

一个天真的错误是假设我们只关心非白球的总和是否为偶数。 这是不够的，因为该操作同时耦合三种颜色，并且可以以非平凡的方式改变奇偶校验模式。 

另一种常见的失败情况是 r、g、b 均为奇数。 例如，r = g = b = 1 且 w = 0。一个运算可将其转换为 (0, 0, 0, 3)。 如果不了解奇偶校验约束，人们可能会错误地认为在将所有内容都简化为白色后答案总是肯定的，但回文的奇偶校验可行性取决于在所有转换后是否最多有一个类别具有奇数计数。 

## 方法

 暴力的观点是重复尝试以所有可能的方式应用该操作，跟踪可达状态并检查是否有任何最终配置可以排列成回文。 这在原则上是正确的，因为它探索了所有有效的变换，但状态空间在颜色之间可能的质量分布方面无限制地增长，并且在深度上呈指数增长。 即使很小的输入也会产生许多中间配置，这使得这是不可行的。 

关键的见解是该操作保留了 r + g + b 模 2 的值。每个操作都会将 r、g、b 中的每一个减一，因此它会同时翻转它们各自的奇偶校验，但会限制它们的组合奇偶校验行为。 更重要的是，形成回文的唯一障碍是优化重新分配为白色后奇数颜色的数量。 白球充当灵活的缓冲区，可以吸收多余的奇偶校验，但除非有额外的白球可用，否则它无法同时解决所有三个奇数计数。 

问题归结为检查我们是否可以使用该操作调整 r、g、b，以便 r、g、b 至多其中一个变为奇数。 该操作会同时更改所有三个奇偶校验，因此我们可以保持奇偶校验不变（通过应用该操作两次）或一次翻转所有三个奇偶校验（通过应用一次）。 因此我们只需要检查r、g、b的奇偶性以及w是否可以补偿剩余的不平衡。 

正确的条件为：利用运算奇偶效应进行最多一次调整后，r、g、b、w中奇数计数的总数最多为1。 

这会产生每个测试用例的恒定时间检查。

 | 暴力模拟| O(exp) | O(1) | O(1) | 太慢了|
 | 奇偶不变解| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们观察到，只有每个计数的奇偶性对于回文安排的可行性才重要。 

我们计算 r、g、b 有多少个是奇数。 设该值为k。

然后我们考虑运营如何改变奇偶校验。 一项操作同时翻转所有三个奇偶校验。 这意味着我们可以保持 k 不变或将其转换为 3 - k，因为翻转所有三个开关会改变每种颜色的奇数。 

我们选择两种可能性中较好的一个，并将其与 w 的贡献结合起来，因为白球可以吸收剩余的不平衡。 

然后我们检查最终的系统总体上是否至多有一个奇数组件。 如果是，则回文排列是可能的，因为所有剩余的奇数计数都可以放置在中心位置，而偶数计数对称地配对。 

如果不是，则在任何序列的操作之后都不可能将所有球排列成回文。 

不变的是，每次操作都保留 r、g 和 b 之间的奇偶关系结构，直到全局翻转，并且白色仅充当灵活的吸收器。 因此，唯一的障碍是我们能否将奇数分量的数量减少到最多一个。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        r, g, b, w = map(int, input().split())

        odd = (r & 1) + (g & 1) + (b & 1)

        if odd <= 1:
            print("Yes")
            continue

        if w > 0:
            print("Yes")
        else:
            print("No")

if __name__ == "__main__":
    solve()
```该方案直接计算三基色的奇偶性。 如果已经满足回文条件（最多1个奇数），则无需进行任何操作。 否则，修复奇偶校验不平衡的唯一方法是使用至少一个操作，这只有在我们有足够的白球引入的灵活性时才有用。 如果存在白球，则可以吸收奇偶调整后剩余的不平衡； 否则，配置仍然无法进行。 

一个微妙的点是我们从不显式地模拟该操作。 这是有意为之的，因为该操作仅通过其奇偶效应起作用，而任何更深入的模拟只会掩盖不变量。

 ## 边缘情况

 关键的边缘情况是 r、g、b 三个都为奇数并且不存在白球。 例如：```
1 1 1 0
```每个操作都需要消耗每种颜色中的一种，但是任何此类操作序列都无法在不引入白色容量的情况下消除基本奇偶校验不平衡。 该算法通过检测奇数计数为 3 且 w 为 0 来检查这一点，从而正确得出“否”。 

另一种情况是所有计数均为偶数时：```
2 4 6 0
```这里奇数计数为0，因此配置立即有效。 该算法返回“是”，而不尝试不必要的转换，完全依赖于奇偶校验结构。 

最后一种情况是白球占主导地位时：```
1 1 1 10
```尽管初始奇偶校验无效，但白球的存在保证了最多一次操作后吸收不平衡的灵活性，因此答案变为“是”。
