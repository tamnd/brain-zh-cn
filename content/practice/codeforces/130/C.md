 ## 解决方案
 ## 问题理解

 我们给出了一个整数序列，需要计算它们的总和。 输入以整数开头`n`，它告诉我们后面有多少个数字。 接下来的每一个`n`lines 包含数组的一个元素。 任务只是将它们全部加在一起并打印结果。 

限制非常小。 该数组最多包含 100 个数字，每个数字都在 1 到 100 之间。即使是最简单的算法也很容易满足限制。 在最坏的情况下，对阵列的线性扫描仅执行 100 次加法，这实际上是瞬时的。 

尽管任务很简单，但仍有一些地方如果不小心实施可能会失败。 

一种常见的错误是在相加之前忘记将输入字符串转换为整数。 例如：```
3
1
2
3
```正确的输出是：```
6
```如果有人不小心连接字符串而不是对整数求和，他们可能会产生`"123"`反而。 

另一个错误是只读取一行`n`而不是阅读全部`n`元素。 考虑：```
5
1
2
3
4
5
```正确答案是：```
15
```仅读取第一个数字的错误实现会错误地输出`1`。 

还有最小尺寸的情况：```
1
42
```答案仍然必须正确计算：```
42
```假设至少两个元素的算法在这里可能会失败。 

## 方法

 最直接的解决方案是蛮力：一一读取每个数字并记录总计。 全部处理完后`n`数字，打印累计和。 

这是有效的，因为问题本身的定义是可加的。 每个元素都独立地对最终结果做出贡献，因此我们不需要重新访问早期的值或存储复杂的状态。 该算法执行准确`n`补充。 和`n ≤ 100`，最坏的情况也只有 100 次操作。 

不需要更复杂的优化。 暴力方法已经是最佳方法，因为每个输入数字都必须至少检查一次。 任何正确的算法都有一个下限`O(n)`跳过一个元素可能会错过部分总和的时间。 

关键的观察结果是该问题没有隐藏结构。 没有查询、更新或排序限制。 单次线性传递是最简单且最快的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 已接受 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取整数`n`，数组中元素的数量。 
2. 初始化变量`total = 0`。 该变量存储迄今为止处理的所有数字的运行总和。 
3. 重复`n`次数：

 1. 读取下一个整数。 
2.添加到`total`。 
4.处理完所有数字后，打印`total`。 

为什么它有效：

 每一步，`total`等于迄今为止读取的所有元素的总和。 最初，没有处理任何元素，因此正确的总和是`0`。 每次迭代都会向运行总和中添加一个新的数组元素，从而保留不变量。 在最后一次迭代之后，每个数组元素都被恰好包含一次，所以`total`等于完整数组的总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

total = 0

for _ in range(n):
    total += int(input())

print(total)
```该程序从阅读开始`n`，它确定后面有多少个整数。 变量`total`存储累计和。 

循环完全运行`n`次。 在每次迭代期间，读取一个整数并立即添加到`total`。 由于约束很小，因此除了标准的快速输入处理之外不需要特殊的优化。 

一个微妙的细节是使用将输入转换为整数`int(input())`。 输入以字符串形式到达，如果转换失败会产生不正确的行为。 

该实现还避免存储整个数组。 由于每个值仅使用一次，因此在读取数字时对其进行处理可保持内存使用量恒定。

## 测试用例```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())

    total = 0

    for _ in range(n):
        total += int(input())

    print(total)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided samples
assert run("5\n1\n2\n3\n4\n5\n") == "15\n", "sample 1"

# minimum-size input
assert run("1\n42\n") == "42\n", "single element"

# all equal values
assert run("4\n7\n7\n7\n7\n") == "28\n", "all equal"

# boundary values
assert run("3\n100\n100\n100\n") == "300\n", "maximum element values"

# off-by-one style case
assert run("2\n1\n100\n") == "101\n", "reads exactly n elements"

# larger case
assert run("5\n10\n20\n30\n40\n50\n") == "150\n", "general accumulation"
```| 测试输入| 预期产出 | 它验证了什么 |

 ## 边缘情况

 考虑尽可能最小的输入：```
1
42
```算法初始化`total = 0`，然后恰好处理一个数字。 

读完后`42`，运行总和变为：```
total = 0 + 42 = 42
```最终打印的答案是：```
42
```这确认循环正确处理单次迭代。 

现在考虑重复值：```
4
7
7
7
7
```执行过程如下：```
0 -> 7 -> 14 -> 21 -> 28
```每个事件都是独立添加的，因此重复不会导致问题。 

最后，考虑最大元素值：```
3
100
100
100
```运行总和的演变如下：```
0 -> 100 -> 200 -> 300
```Python 整数可以轻松处理这些值，因此不存在溢出风险。 算法正确输出：```
300
```
