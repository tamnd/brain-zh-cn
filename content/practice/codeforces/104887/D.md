 ## 解决方案
 ## 问题理解

 我们得到了与位置 1 到 n 相关的多组优势，并且我们可以输出这些位置的排列。 在我们修复排列之后，一个独立的进程尝试使用增加长度为 k 的连续段上的值的操作来满足每个位置的所需值。 

每个操作都会在当前排列中选择一个长度为 k 的窗口，并将该窗口中的每个元素递增 1。 固定排列的成本是使位置 i 对于每个 i 至少达到 a[i] 所需的此类操作的最小数量。 我们的任务不是计算给定排列的成本，而是构造一个排列，使该成本尽可能大。 

关键的困难在于成本取决于在大小为 k 的重叠窗口内分组的需求量。 如果放置较大的值，以便在每个操作中可以一起覆盖许多值，则操作总数会减少。 如果它们的分布方式迫使窗口反复“错过”高需求的位置，那么成本就会增加。 

约束允许 n 最大为 2×10^5，这排除了尝试所有排列或模拟许多候选过程的任何方法。 即使每个排列的 O(n²) 推理也太慢，因此解决方案必须在单遍或接近线性的时间内构造排列。 

当 k = 1 时，会出现微妙的边缘情况。每个操作仅影响单个元素，因此成本变为所有 a[i] 的总和，与顺序无关。 在这种情况下，任何排列都是最佳的，因此构造必须在不依赖分组行为的情况下仍然保持有效。 

当 k = n 时会出现另一种边缘情况。 每个操作同时影响所有位置，因此成本变为 max(a[i])。 再次强调，任何排列都有效，并且构造不应承担局部性问题。 

真正的困难在于中间 k，其中重叠的窗口会产生滑动的“覆盖容量”效应，而排序决定了大需求的摊销效率。 

## 方法

 直接方法会尝试评估给定排列的成本。 对于固定的安排，可以贪婪地模拟需要多少段操作。 一个常见的想法是从左到右处理，只要某个位置仍低于其目标，就重复应用操作。 然而，在最坏的情况下，这种模拟的成本已经是 O(n·max(a))，因为每个增量仅贡献一个单位的进度，而 a[i] 可以大到 10^9。 更关键的是，我们需要测试许多排列，这使得这完全不可行。 

结构性的洞察来自于颠倒观点。 我们不去思考“给定一个排列，我们会得到什么成本”，而是问“哪些安排迫使滑动窗口效率最低”。 每个操作贡献 k 个增量，分布在相邻位置上。 如果大量需求聚集在一起，则单个操作可以同时帮助许多大值。 为了最大限度地提高成本，我们希望防止这种聚集，并确保高值尽可能地干扰彼此的覆盖范围。 

这变成了由大小为 k 的窗口引起的间隔上的经典贪婪排序问题。 每个位置都可以被认为是参与 k 个连续的窗口，因此将较大的值放置在相距较远的位置往往会增加满足它们所需的操作数量，因为没有一个窗口会重复受益于许多大的需求。

一个关键的观察结果是，最差的排列是通过在排列布局中以 k 为模的残差类上均匀分布大值来实现的。 这确保了任何长度为 k 的窗口最多与每一类中的一个非常大的值相交，从而限制了共享覆盖范围。 实际上，这是通过按值对索引进行排序并以循环方式将它们分配到 k 个桶中，然后连接桶来实现的。 

这种结构确保大的 a[i] 值尽可能被至少 k 个位置分隔，迫使进程“重新应用”操作比分组操作要多次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 排列的强力模拟 | O(n!·n·max(a)) | O(n!·n·max(a)) | O(n) | 太慢了|
 | 贪婪循环分布| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们构造索引 1 到 n 的排列。 

1. 将所有索引按所需值 a[i] 降序排序。 

这确保我们首先放置最“昂贵”的位置，因为它们决定了强制操作的数量。 
2. 创建k个空桶。 

这些桶代表最终排列中的残留类别，确保高值之间的分离。 
3. 迭代排序后的索引，并按循环顺序将它们一一分配到桶中。 

第一个最大的数据进入存储桶 0，然后进入存储桶 1，依此类推。 

这保证了在最终连接中连续的大值至少被 k 个位置分隔开。 
4. 按照从桶 0 到桶 k−1 的顺序连接所有桶，形成最终的排列。 

这会产生一个布局，其中每个存储桶形成一个间隔子序列，并将它们组合起来保留分离属性。 

这样做的原因是每个长度为 k 的窗口最多可以与大值“密集”区域中每个存储桶中的一个元素相交。 由于大值分布在各个存储桶中，因此没有一个窗口可以重复覆盖许多高需求的索引。 这迫使最小操作数增加，因为覆盖范围无法跨多个高 a[i] 位置有效地重用。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

idx = list(range(n))
idx.sort(key=lambda i: a[i], reverse=True)

buckets = [[] for _ in range(k)]

for t, i in enumerate(idx):
    buckets[t % k].append(i + 1)

ans = []
for b in buckets:
    ans.extend(b)

print(*ans)
```实施直接跟随构造。 我们通过减少 a[i] 对索引进行排序，这确保我们首先处理要求最高的位置。 循环分配将它们均匀地分布在 k 个桶中，这是防止聚类的核心机制。 

最终的串联很重要：它保留每个存储桶内的内部顺序，同时确保来自不同存储桶的元素以大约 k 的距离交错。 需要在输出中使用基于 1 的索引，因为问题需要标记为从 1 到 n 的位置。 

## 工作示例

 考虑一个输入，其中 n = 5、k = 3，值为 [7, 77, 2, 22, 222]。 

按值对索引进行排序后，我们得到与值对应的索引：

 222（索引 5）、77（索引 2）、22（索引 4）、7（索引 1）、2（索引 3）

 我们循环分配到 k = 3 个桶中。 

| 步骤| 索引 | 价值| 桶分配|
 | ---| ---| ---| ---|
 | 1 | 5 | 222 | 222 桶 0 |
 | 2 | 2 | 77 | 77 桶 1 |
 | 3 | 4 | 22 | 22 桶 2 |
 | 4 | 1 | 7 | 桶 0 |
 | 5 | 3 | 2 | 桶 1 |

 桶变成：

 存储桶 0: [5, 1]

 存储桶 1: [2, 3]

 桶 2：[4]

 连接得到： [5, 1, 2, 3, 4]

 这与将大值（5 和 2）分开的排列相匹配，确保大小为 3 的窗口无法有效地重复覆盖这两个值。 

第二个示例：n = 6，k = 2，值 [1, 100, 2, 99, 3, 98]

 排序索引：2,4,6,3,5,1

 桶：

 存储桶 0：[2,6,5]

 存储桶 1：[4,3,1]

 最终排列：[2,6,5,4,3,1]

 这种交替强制任何长度为 2 的窗口混合高值和中值，而不是将所有高值分组在一起。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log n) | O(n log n) | 排序索引占主导地位，桶分配是线性的 |
 | 空间| O(n) | 存储桶和索引列表 |

 约束最多允许 2×10^5 个元素，因此 O(n log n) 构造完全在限制范围内。 内存使用呈线性且稳定。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    idx = list(range(n))
    idx.sort(key=lambda i: a[i], reverse=True)

    buckets = [[] for _ in range(k)]
    for t, i in enumerate(idx):
        buckets[t % k].append(i + 1)

    ans = []
    for b in buckets:
        ans.extend(b)

    return " ".join(map(str, ans))

# provided sample
assert run("5 3\n7 77 2 22 222\n") == "5 1 2 3 4", "sample 1"

# all equal values
out = run("4 2\n5 5 5 5\n")
assert sorted(out.split()) == ["1","2","3","4"]

# k = 1
out = run("4 1\n1 100 2 99\n")
assert sorted(out.split()) == ["1","2","3","4"]

# k = n
out = run("3 3\n10 20 30\n")
assert sorted(out.split()) == ["1","2","3"]

# descending already
out = run("5 2\n5 4 3 2 1\n")
assert sorted(out.split()) == ["1","2","3","4","5"]

 ## 边缘情况

 当 k = 1 时，每个操作仅影响单个位置，因此索引之间不存在交互。 该算法仍然排序并分配到一个桶中，产生所有索引的简单排列。 由于只有一个桶，桶的结构会正确退化。 

当 k = n 时，每个操作都会影响整个数组，因此相对顺序对可行性没有影响。 该构造仍然输出有效的排列，因为它仅重新排列索引而不假设局部性问题。 

当所有 a[i] 相等时，位置之间没有有意义的区别。 循环分配只是产生任意排序，这与所有排列在对称要求下产生相同成本的事实是一致的。
