 ## 解决方案
 ## 问题理解

 我们正在研究一个$r \times c$网格，其中一些单元格包含士兵。 目标是准确放置$m$士兵，使特定的“破坏游戏”具有非常精确的难度。 

该游戏中的单个动作包括选择一行或一列并删除整行中的每个士兵。 我们可以重复这个操作。 配置的弹性是指移除所有士兵所需的此类移动的最少数量。 

因此，任务不是动态地最小化或最大化任何东西，而是构建一个网格，以便清除它的最佳策略恰好使用$k$移动，或报告不存在此类安排。 

输入尺寸很小（$r, c \le 25$），但值$k$可以大到$10^9$。 这立即意味着大多数问题是组合问题而不是强力搜索。 任何依赖于探索行或列子集或模拟策略的解决方案只有在独立于$k$， 自从$k$其本身可能远大于网格尺寸。 

一个微妙的边缘情况是$k$可以超过两者$r$和$c$。 这是不可能实现的，因为一次移动至少会删除一整行或一列，并且只有$r + c$总共有意义的不同选择。 事实上，弹性的真正上限受到行和列之间的覆盖结构的严格限制，而不是受$m$。 

另一个边缘情况是当$m$非常小或非常大。 如果$m = 0$，答案通常是零步，但在这里$m \ge 1$。 如果$m = rc$，每个单元格都被填充，弹性仅取决于网格尺寸，而不取决于放置的灵活性。 

主要困难在于我们必须将精确的“行列覆盖复杂性”编码到占用的单元格集中。 

## 方法

 如果我们用蛮力的方式思考，我们会尝试每一种可能的放置方式$m$士兵并计算覆盖他们所需的最小行/列删除数。 对于每种配置，这本质上是行和列上的命中集问题。 即使对于固定网格，评估确切的最小移动次数也需要推理每一步删除行或列是否更便宜，这已经建议对子集进行搜索。 

可能的配置数量为$\binom{rc}{m}$，即使对于$r, c \le 25$。 所以暴力破解是不可能的。 

关键的观察结果是运营结构极其严格。 每次移动都会删除整行或整列。 这意味着任何策略都对应于选择一些行和列的集合，其联合覆盖所有士兵单元。 移动次数是此类选择的最小大小。 

那么问题就变成了：在行和列之间构造一个二分重合结构，使得这个二分图中的最小顶点覆盖大小等于$k$，同时还控制我们放置的边（士兵）数量。 

这就是小网格尺寸变得重要的地方。 由于最多有 25 行和 25 列，因此“独立约束”的最大可能数量以每边 25 为界。 任何超出此范围的构建都必须依赖于强制退化或不可能性条件。 

考虑这个问题的标准方法是将行和列解释为二部图的两个分区。 一名士兵在$(i, j)$是行之间的边$i$和列$j$。 移动会删除一个顶点，覆盖所有边意味着选择一个顶点覆盖。 根据柯尼希定理，在二部图中，最小顶点覆盖等于最大匹配。 因此，弹性正是二分图中最大匹配的大小。 

这完全重新构建了问题：我们被要求构造一个二分图$m$边，使其最大匹配尺寸恰好为$k$。 

现在结构更加清晰了。 匹配尺寸不能超过$\min(r, c)$，所以立即如果$k > \min(r, c)$，答案是不可能。 

另一方面，我们必须确保至少有$k$不相交的行列对，并且无法形成更大的匹配。 

一个干净的构建思想是明确地嵌入一个$k \times k$对角线匹配，至少保证匹配尺寸$k$，然后小心地添加剩余的$m-k$边缘的方式不会增加匹配大小。 标准技巧是将所有额外的边放置在二部图已经“饱和”的部分内，这样它们就不会引入新的增广路径。 

最简单的安全结构是：

 我们选择$k$行和$k$列，在它们之间形成完美匹配，然后可选择仅在这些列内填充其他单元格$k$行和$k$列。 任何额外的边都被限制在已经完全活动的子图中，因此它不能将最大匹配增加到超出$k$。 

这降低了在 a 内进行简单计数的可行性$k \times k$子网格。 

我们还必须确保$m$至少是$k$，因为至少$k$需要边缘来支持尺寸匹配$k$，最多$k^2$限制区域中存在边缘。

 ## 算法演练

 我们将任务重新表述为在行和列之间构建二分图。 

1.首先检查是否$k > \min(r, c)$。 如果是这样，则尺寸不匹配$k$这是可能的，因为我们无法配对比现有更多的行和列。 
2.接下来检查是否$m < k$。 尺寸的搭配$k$至少需要$k$边缘，所以这立即是不可能的。 
3. 然后我们重点构建一个$k \times k$原始网格内的活动子网格。 我们选择第一个$k$行和第一行$k$列。 
4. 地点$k$对角细胞上的士兵$(i, i)$为了$0 \le i < k$。 这至少保证了尺寸的匹配$k$，因为每个行列对都是独立的。 
5. 现在我们还需要放置$m - k$额外的士兵。 我们在里面任意填写$k \times k$块，逐行扫描，如果需要的话跳过对角线，直到我们精确到达$m$总兵数。 
6. 输出构建的网格。 

这样做的原因是所有边都完全包含在大小为的二部图中$k \times k$，所以最大可能的匹配至多是$k$。 由于我们明确创建了$k$不相交的边，匹配完全正确$k$。 

### 为什么它有效

 网格产生一个二分图，其中行和列是两个分区，士兵是边。 弹性等于最小顶点覆盖的大小，这等于二分图中的最大匹配大小。 

我们的构造同时强制执行两个属性。 首先，我们明确构建$k$使用对角线不相交的边，至少保证大小匹配$k$。 其次，我们将所有边限制为$k \times k$子图，它限制任何匹配的上限$k$。 由于两个边界都满足，因此匹配的大小恰好是$k$。 同一子图中的附加边不能增加匹配，因为只有$k$行和$k$列可用，因此任何匹配都不能超过该基数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        r, c, m, k = map(int, input().split())

        if k > min(r, c) or m < k:
            print("NO")
            continue

        grid = [['.' for _ in range(c)] for _ in range(r)]

        # build k diagonal matching in top-left k x k
        placed = 0
        for i in range(k):
            grid[i][i] = '#'
            placed += 1

        # fill remaining edges inside k x k
        for i in range(k):
            for j in range(k):
                if placed == m:
                    break
                if grid[i][j] == '.':
                    grid[i][j] = '#'
                    placed += 1
            if placed == m:
                break

        print("YES")
        for row in grid:
            print("".join(row))

if __name__ == "__main__":
    solve()
```解决方案首先要拒绝不可能的情况，其中$k$超过可用行数或列数，或者我们甚至没有足够的士兵来支持$k$尺寸匹配。 

网格初始化为空，然后我们放置一个强制结构：对角线$k$左上角方块中的士兵。 这强制执行$k$独立的行列配对。 

然后，我们小心地将剩余的士兵仅添加到同一个士兵中$k \times k$地区。 这个细节很重要，因为如果新的行或列变得可用，扩展到该区域之外可能会引入额外的匹配可能性。 限制所有内容可确保匹配上限保持固定。

 ## 边缘情况

 一个关键的边缘情况是当$k = \min(r, c)$。 例如：```
3 5 m 3
```这里的构造必须充分利用所有可用的行或列。 对角线仍然有效，但二分结构没有松弛。 该算法仍然放置一个$3 \times 3$块并仅填充其中。 即使剩余的网格未被使用，也没关系，因为匹配已经饱和。 

另一种情况是当$m = k$。 在这种情况下，我们只放置对角线并立即停止。 任何增加更多结构的尝试都会违反对士兵总数的限制。 匹配仍然准确$k$，因为每个边缘对于构建来说都是至关重要的。 

最后，当$m = k^2$，整个$k \times k$块已满。 即使在这种极端密度下，匹配也不会超过$k$，因为除了可用行和列的数量之外，无法形成额外的独立行列配对。
