 ## 问题理解

 我们在平面上有一个起点和固定的移动顺序。 每个动作都有两条信息：最大长度$K_i$以及方向类型的约束，水平或垂直。 对于水平移动，我们必须向东或向西移动，我们可以选择从 1 到 的任何整数步长$K_i$。 对于垂直移动，我们同样选择向北或向南，长度在 1 和$K_i$。 

任务是决定我们是否可以同时选择方向和步长，以便在按顺序执行所有移动后，我们正好在原点结束。 如果可能的话，我们还必须构造一个有效的选择序列。 

约束允许最多$2 \cdot 10^5$跨所有测试用例，因此任何解决方案都必须在每个测试用例的线性或接近线性时间内运行。 任何试图独立枚举方向或长度分配的方法都会呈指数级爆炸，因为每次移动都有两个方向选择，并且最多可达$K_i$长度选择。 

一个微妙的问题是，除非我们明确使用方向自由度，否则移动不会围绕零对称。 每次移动都会沿着固定轴贡献一个正整数或负整数。 这意味着每一步都是一个整数变量，被限制在两个区间的并集中：$[-K_i, -1]$或者$[1, K_i]$。 主要的困难是协调这些选择，使总和符合固定目标。 

当贪婪方法过早确定方向时，就会出现常见的失败情况。 例如，如果我们总是尝试使用尽可能大的步长来减少剩余距离，那么我们最终可能会遇到剩余移动由于其范围灵活性不足而无法补偿的情况。 另一个失败来自于忽视了一些举措可能需要作为小调整而被“浪费”，即使它们有很大的调整。$K_i$。 

## 方法

 暴力解释将每次移动视为独立选择符号和长度，然后检查所得总和是否等于所需的位移。 这导致搜索空间的大小大致为$\prod (2K_i)$，即使对于小规模来说也是不可行的$n$。 即使将长度限制为固定值也会留下$2^n$符号配置，仍然是指数级的。 

关键的观察结果是水平和垂直分量是独立的。 总水平位移仅取决于水平移动，垂直位移仅取决于垂直移动。 这将问题简化为两个独立的一维结构。 

现在问题变成：给定值$K_i$,给每个变量赋值$x_i$任一整数$[1, K_i]$或者$[-K_i, -1]$，使它们的总和等于目标$S$。 该结构是每个变量的有界区间，带有禁止的零。 重要的简化是，可行性仅由可实现总和的范围决定，而不是由组合奇偶性或子集结构决定。 由于每个变量都可以取除零之外的连续区间内的所有整数，因此只要保持全局可行性界限，我们就可以随时进行局部调整。 

任意前缀的可行总和范围为$[-\sum K_i, \sum K_i]$。 这就给出了必要条件。 主要挑战是在线构建值，同时保留剩余后缀的可行性。 

标准的建设性思想是按顺序处理动作，同时保持剩余的所需金额。 在每一步中，我们都会为当前移动选择一个值，以确保使用剩余容量可以实现剩余要求。

 ## 算法演练

 我们独立求解水平轴和垂直轴。 每边都是相同的，因此我们描述具有目标和的单个序列的过程$S$。 

1. Split 根据水平或垂直方向分为两个数组。 对于每个组，我们只关心沿该轴的目标总和，即变为$-x$或者$-y$。 
2. 计算后缀和$K_i$。 让$rem[i]$是移动的剩余最大贡献总额$i$向前。 该值代表我们在位置之后仍然可以添加或减去的最大幅度$i$。 
3. 维护运行变量$R$，最初等于目标总和$S$。 这代表着未来的选择还需要实现多少位移。 
4. 流程从左向右移动。 移动时$i$，我们必须选择$x_i \in [-K_i, -1] \cup [1, K_i]$。 我们尝试分配一个保持条件的值$|R - x_i| \le rem[i+1]$true，确保后缀仍然可以补偿。 
5. 如果$R$是正数，我们尝试通过选择正数来减少它$x_i$。 我们从$x_i = \min(K_i, R)$，因为这最符合其余的要求。 如果这种选择破坏了可行性，我们会减小幅度或翻转符号并尝试相反的方向。 
6. 如果$R$是负数，我们对称地尝试使用负数将其向上移动$x_i$，从$x_i = -\min(K_i, -R)$，再次检查可行性并根据需要进行调整。 
7.固定后$x_i$， 更新$R := R - x_i$并继续。 

这样做的原因是，在每一步中，我们都保留了剩余所需总和位于后缀的可实现区间内的不变量。 由于每个后缀都可以贡献连续对称范围内的任何值，因此只要我们不打破界限，保持这个不变性就可以保证余数存在有效的分配。 

禁止的零不会产生干扰，因为我们永远不需要将零作为所需值传递； 我们只需要确保每个单独的分配保持在对称的非零区间内，该区间始终包含至少一个与可行性一致的有效整数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_group(items, target):
    n = len(items)
    suffix = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suffix[i] = suffix[i + 1] + items[i][0]

    res = [0] * n
    R = target

    for i in range(n):
        k = items[i][0]

        # try positive first
        for sign in (1, -1):
            lo = 1
            hi = k
            if sign == -1:
                lo, hi = -k, -1

            # choose closest to R in that signed interval
            if sign == 1:
                x = min(hi, max(lo, R))
            else:
                x = max(lo, min(hi, R))

            if abs(R - x) <= suffix[i + 1]:
                res[i] = x
                R -= x
                break

    return res

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, x, y = map(int, input().split())

        H = []
        V = []

        for _ in range(n):
            k, d = input().split()
            k = int(k)
            if d == 'H':
                H.append([k, 'H'])
            else:
                V.append([k, 'V'])

        hx = solve_group([[k, d] for k, d in H], -x)
        vy = solve_group([[k, d] for k, d in V], -y)

        if hx is None or vy is None:
            out.append("NO")
            continue

        out.append("YES")

        hi = vi = 0
        for k, d in H + V:
            if d == 'H':
                if hx:
                    val = hx.pop(0)
                    if val > 0:
                        out.append(f"{val} E")
                    else:
                        out.append(f"{-val} W")
            else:
                if vy:
                    val = vy.pop(0)
                    if val > 0:
                        out.append(f"{val} N")
                    else:
                        out.append(f"{-val} S")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```实现的核心是后缀可行性数组，它可以防止贪婪决策陷入构造困境。 每个步骤都通过显式检查剩余所需总和是否适合剩余总容量来选择局部合理但仍全局安全的值。 

一个常见的实现陷阱是将轴分解与重建顺序混合在一起。 由于输出必须遵循原始顺序，因此在打印时必须小心地交错水平和垂直解决方案。

 ## 边缘情况

 一个关键的边缘情况是当目标恰好位于可行性边界时，这意味着所有的总和$K_i$等于绝对目标。 在这种情况下，每一个动作都被迫在一个一致的方向上达到最大程度。 该算法自然地处理这个问题，因为可行性检查$|R - x_i| \le rem[i]$每一步只允许一个有效的延续。 

另一种情况是早期走势较大但后期走势均较小。 幼稚贪婪的选择可能一开始就消耗过多，而调整能力不足。 基于后缀的约束通过拒绝任何会使剩余需求超出后缀仍然可以产生的需求的分配来防止这种情况发生。
