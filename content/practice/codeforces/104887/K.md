 ## 解决方案
 ## 问题理解

 我们在队列中给出了固定的学生顺序。 每个学生都需要固定的时间来完成考试，并且有$k$可以并行处理学生的教师。 学生总是试图立即开始：如果当他们到达前面时老师有空，他们就会接受；如果老师有空，他们就会接受。 否则他们会等到某个教练完成。 

关键的观察结果是队列顺序永远不会改变，并且没有学生可以超越另一个学生。 这使得系统相当于一个作业流$k$具有严格到货顺序限制的相同机器。 我们唯一的自由就是选择$k$，并行服务器的数量。 

对于固定的$k$，该过程要么在时间内完成$T$或者它没有。 该问题对每个测试用例提出两件事：首先确定是否可以在$T$，如果是，求最小值$k$这使得这成为可能。 

约束条件很大：最多$n = 150{,}000$每个测试用例和总计$N \le 450{,}000$。 每个$a_i$可以大到$10^{16}$。 这立即排除了任何尝试逐步建模时间的模拟。 即使每个教练对每个事件进行模拟也会太慢，因为事件可能会$O(n \log n)$或者更糟，我们可能需要测试许多值$k$。 

该解决方案必须评估给定的可行性$k$在线性或近线性时间内，然后搜索最小值$k$，通常使用二分查找。 

当一个非常大的情况时，就会出现微妙的边缘情况$a_i$超过$T$。 在这种情况下，无论什么配置都不起作用$k$，因为即使有无限的导师，单个学生也无法及时完成。 另一个边缘情况是当$T$很小但是$n$很大； 除非我们正确地模拟完成时间，否则像“继续分配下一个免费讲师”这样天真的贪婪假设就会失败。 

## 方法

 蛮力方法会尝试增加$k$从1开始，每次模拟整个过程。 对于固定的$k$，我们将维护所有教师的完成时间，并将每个学生分配给最早可用的教师。 最小堆自然会对此进行建模。 

对于每个测试用例，模拟一个值$k$需要$O(n \log k)$，因为我们为每个学生从堆中推送和弹出。 如果我们尝试所有$k$最多$n$，这变成了$O(n^2 \log n)$，这太慢了$n = 150{,}000$。 

关键的见解是可行性是单调的$k$。 如果我们能在$T$使用$k$导师，那么我们也可以完成使用$k+1$教练，因为增加容量永远不会有坏处。 这将问题转化为搜索$k$。 

我们仍然需要有效的可行性检查。 关键的简化是避免显式地对队列进行建模，而是仅模拟讲师的可用时间。 每个教练都会保留空闲时间。 对于每个学生，我们按顺序将他们分配给最早有空的老师。 如果最早的空闲时间大于他们开始的当前时间，他们必须等待； 否则它们会在当前时间立即开始。 完成时间相应更新。 

这正是在相同机器上的贪婪调度过程，其释放时间等于学生到达前面的时间，这自然是顺序的。 

因此，我们结合了两种想法：最小堆可行性检查和二分搜索$k$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 全部尝试$k$+ 模拟 |$O(n^2 \log n)$|$O(n)$| 太慢了 |
 | 二分查找+堆模拟|$O(n \log n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 ### 固定的可行性检查$k$1. 初始化一个最小堆$k$零，表示所有教师最初在时间 0 都是空闲的。该模型在开始时具有相同的可用性。 
2. 按排队顺序处理学生。 对于学生$i$，提取可用时间最少的讲师$t$。 该讲师最早有空，因此他们是唯一可以立即开始的候选人。 
3. 学生可以按时开始$\max(t, 0)$，但由于我们跟踪绝对时间进展，因此我们将其解释为从时间开始$t$。 他们的完成时间变成$t + a_i$。 
4. 将更新后的完成时间推回堆中，因为该讲师在该时间之前现在很忙。 
5. 跟踪所有学生的最长完成时间。 如果在任何一点超过$T$，我们可以提前停止以提高效率，因为日程安排无法通过未来的作业来修复。 
6.所有学生处理完毕后，返回最大完成时间是否最多$T$。 

### 搜索最小值$k$1.如有单项$a_i > T$，立即输出NO，因为该学生独自一人无法及时完成。 
2.否则二分查找$k$从 1 到$n$。 对于每个中点，运行可行性检查。 
3.最小的$k$返回 true 就是答案。 

### 为什么它有效

 堆不变量是在任何时刻它都包含每个讲师当前的完成时间。 每项作业始终使用可用的讲师
