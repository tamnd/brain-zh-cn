 ## 解决方案
 ## 问题理解

 我们有两个长度相等的二进制数组。 我们可以从每个数组中选择一个连续的段，并且每个段的唯一限制是其长度必须落在给定范围内。 选择两个段后，我们计算它们中出现的零和一的数量。 目标是确定是否存在两个段的选择，使得 0 的总数等于 1 的总数。 

重写条件的一个有用方法是从平衡的角度思考。 对于任何段，将其值定义为 1 的数量减去 0 的数量。 两个所选段的总零数等于总零数的要求与要求这两个段值的总和为零的要求完全相同。 所以我们正在寻找数组中的一个段`a`和数组中的一个段`b`，在各自的长度限制内，使得它们的“不平衡”完美抵消。 

这些限制使得对所有段进行暴力破解是不可能的。 每个数组跨测试用例最多有 200,000 个元素，并且最多有 100,000 个测试用例。 即使每个测试用例的段的二次枚举也将远远超出任何可行的限制。 每个测试用例的线性扫描已经是预期的规模。 

常见的故障模式是忽略来自两个不同阵列的段。 一种简单的解决方案可能会尝试预先计算一个数组中的所有段总和，然后将它们与另一个数组进行匹配，但忘记长度约束会破坏正确性。 另一个微妙的错误是只考虑前缀和或只考虑最小和最大段和； 两者都失去了对允许的段长度的依赖，这在这里是必不可少的。 

## 方法

 蛮力的想法很简单。 我们枚举了中的每个有效段`a`其长度介于`x1`和`y1`，计算其余额，然后枚举中的每个有效段`b`其长度介于`x2`和`y2`，计算其余额，并检查一对总和是否为零。 这是可行的，因为它直接遵循定义，但速度太慢。 在最坏的情况下，每个数组都有 O(n²) 个段，因此即使仔细实现，在朴素叉积视图中，比较总数也变为 O(n⁴)。 

关键的观察结果是，条件仅取决于转换后的数组的段和。 如果我们将每个二进制数组转换为一个数组，其中`0 → -1`和`1 → +1`，那么每个段的总和就是它的余额。 问题变成：是否存在两个允许的段，每个数组各一个，其总和为零。 

这可以被重新定义为在长度约束下可实现的线段总和上的集合交集问题。 我们不枚举所有段，而是只关心每个数组可实现哪些总和。 对于固定数组和固定长度间隔，我们可以使用前缀和上的滑动窗口有效地确定所有段和。 挑战在于检查是否有来自`a`它的否定存在于`b`。 

我们避免显式存储所有可能的总和。 相反，我们扫描一个数组，在哈希集中标记可实现的段和，然后扫描另一个数组并测试补集。 由于分段总和取决于前缀差异，因此可以在 O(1) 内计算每个分段总和，并且每个数组总体贡献 O(n) 个候选。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每次测试 O(n²) | O(n²) | 太慢了|
 | 前缀枚举+哈希| 每次测试 O(n) | O(n) | 已接受 |

 ## 算法演练

 我们对每个二进制值进行变换，使 0 贡献 -1，1 贡献 +1。 这使得每个段和代表 1 和 0 之间的不平衡。 

然后，我们计算两个数组的前缀和，以便可以在恒定时间内提取任何段和。 

对于每个数组，我们迭代所有有效的段长度。 对于固定长度`len`，我们在数组上滑动一个窗口，并使用前缀差异计算段总和。 对于数组`a`，我们将所有可实现的段总和存储在哈希集中。 我们对数组重复相同的过程`b`。 

最后，我们检查是否存在一个值`s`在集合中`a`这样`-s`存在于集合中`b`。 如果是，我们输出 YES，否则输出 NO。 

微妙的一点是我们必须独立地遵守两个数组的长度约束。 这些集合仅根据有效的窗口大小构建，否则我们将包括无法出现在实际解决方案中的无效候选者。 

### 为什么它有效

 每个有效段都唯一对应于一个前缀差异，因此当我们按长度和起始索引枚举时，不会错过任何有效的候选者。 到 ±1 的转换保证了两个段之间的 0 和 1 相等相当于和抵消。 由于我们在相同的约束下检查两个数组中所有可实现的和，因此零和对的存在相当于检测两个集合中的匹配否定。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_sums(arr, x, y):
    n = len(arr)
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + (1 if arr[i] == 1 else -1)

    res = set()

    for length in range(x, y + 1):
        for i in range(n - length + 1):
            s = pref[i + length] - pref[i]
            res.add(s)

    return res

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, x1, y1, x2, y2 = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        sa = build_sums(a, x1, y1)
        sb = build_sums(b, x2, y2)

        # check intersection via negation
        ok = False
        if len(sa) > len(sb):
            sa, sb = sb, sa

        for v in sa:
            if -v in sb:
                ok = True
                break

        out.append("YES" if ok else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```前缀和数组对累积不平衡进行编码，以便在 O(1) 内计算段和。 长度和起始索引上的嵌套循环确保仅考虑有效间隔。 交换集合可以通过迭代较小的集合来稍微降低查找成本。 

否定检查是两个分部余额必须取消的条件的直接转换。

 ## 边缘情况

 当两个数组完全由相同的位组成时，就会出现一种边缘情况。 如果所有值都为零，则每个段的不平衡性为零，因此任何有效对都有效。 该算法正确地将零插入到两个集合中，并在零处找到匹配项。 

当段长度范围排除除一个长度之外的所有长度时，会出现另一种边缘情况。 该算法仍然仅枚举该长度，因此不会泄漏无效段。例如，如果两个范围都是`[1,1]`，仅考虑单个元素，平衡检查减少为比较数组中的各个位，这是由前缀逻辑自然处理的。 

第三种边缘情况是一个数组可以产生正负段和，而另一个数组完全是单边的。 在这种情况下，否定检查永远不会成功，因为值分布不会以对称方式重叠。 基于集合的方法可以正确捕获这种不对称性，而不需要特殊处理。
