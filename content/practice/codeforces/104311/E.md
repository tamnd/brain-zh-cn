 ## 解决方案
 ## 问题理解

 我们给出了一组整数，其中值`i`准确地出现`m_i`次。 从这个多重集中，我们考虑完整扩展数组的每种可能的排列。 对于每个排列`a`，我们通过从左到右扫描前缀并跟踪迄今为止看到的最小值来计算一个分数。 每当此前缀最小值减少到新值时，该值就会乘以分数。 同样，分数是扫描期间成为前缀最小值的所有不同值的乘积。 

所以如果前缀最小值的序列是`4, 4, 2, 2, 1, 1`，不同的值是`4, 2, 1`，分数就是他们的乘积。 

任务是计算该分数在多重集的所有不同排列上的总和，模`998244353`。 

输入大小在两个不同的维度上都很大。 不同值的数量`n`跨测试可以达到一百万，而所有值的总重数可以达到一千万。 这立即排除了任何迭代排列甚至显式构造序列的解决方案。 甚至`O(total permutations)`或者任何依赖于阶乘增长的事情都是不可能的。 我们需要在每次测试中以大致线性或接近线性的时间工作的东西。 

一个微妙的问题是分数取决于前缀最小值，这是排序的全局属性。 天真地单独处理每个值的贡献是失败的，因为尽早放置少量的贡献会抑制所有较大的贡献成为前缀最小值。 

典型的失败案例来自于假设每个值独立贡献。 例如，如果所有数字都是不同的，一个天真的想法可能是根据成为前缀最小值的概率将每个值视为贡献。 但是排序依赖破坏了独立性：放置一个`1`早期完全删除所有其他贡献。 

## 方法

 强力方法将枚举多重集的所有排列，计算每个排列的前缀最小值，乘以不同的最小值，并对结果求和。 即使对于中等大小，这种情况也会爆炸，因为排列的数量是`(sum m_i)! / ∏ m_i!`，即使对于很小的输入，这也是一个天文数字。 计算每个排列的前缀最小值是线性的，因此这种方法是没有希望的。 

关键的观察结果是，前缀最小过程仅取决于“记录最小值”递减的相对顺序。 一旦某个值成为当前最小值，所有未来的贡献仅取决于稍后是否出现更小的值。 这表明我们首先确定最小值，然后推理如何在不影响最小值链的情况下出现更大的值。 

我们扭转思路：我们不构建排列，而是构建从小到大的前缀最小值序列。 一个值`x`出现在乘积中当且仅当在某个位置它成为迄今为止看到的最小值，这相当于新的全局最小值的第一次出现恰好是`x`。 这对应于一种结构，其中每个新的最小值都会阻止所有较大的值，直到它出现为止。 

我们从小到大处理值。 假设我们目前处于价值`i`。 如果我们决定`i`是某个阶段的最小值，则所有值都大于`i`在我们放置至少一个之前都是无关紧要的`i`。 这表明我们有一个 DP，其中我们维护可以构建当前最小值为的序列的多种方法`i`或更大，同时考虑到同等价值的安置。 

关键的组合简化是将过程视为构建由新最小值分隔的块。 每次我们引入新的最小值`i`，我们有效地选择了第一个位置`i`相对于所有先前放置的元素出现。 剩余出现的较大值可以在该屏障之上自由交错。 这将问题简化为乘以独立“后缀安排”的贡献，并根据每个最低级别可以引入的方式进行加权。 

重新排列组合后，结果简化为具有类似阶乘贡献的值上的前缀 DP，其中我们维护将所有较高值插入由较低最小值确定的槽中的方法数量，并累积贡献乘以`i`什么时候`i`成为有效最小值。 

这产生了线性扫描`1`到`n`通过阶乘预计算和运行组合系数来跟踪有多少排列与当前最小结构保持一致。

 ## 算法演练

 我们处理来自`n`下降到`1`，维护我们可以将已处理的较大值排列到尚未强制出现较小值的序列中的多种方式。 

由于重复需要多项系数，我们预先计算阶乘和逆阶乘直至总长度。 

我们维护一个运行变量`ways`，最初等于`1`，表示空集的排列方式数。 我们还维护`remaining`，当前由大于当前索引的值填充的位置数。 

对于每个值`i`从`n`下降到`1`，我们执行以下操作：

 1. 我们考虑插入所有副本`i`进入当前较大元素的排列。 有`remaining + m_i`插入后的总槽位，我们选择位置`m_i`的副本`i`。 这贡献了二项式因子`C(remaining + m_i, m_i)`。 
2. 在所有这些安排中，价值`i`当第一次出现时，恰好成为新的可能的前缀最小值`i`放置在任何较小值之前（尚未插入到此反向扫描中）。 这贡献了一个乘法因子`i`到配置的分数，其中`i`作为最小边界处于活动状态。 
3. 我们通过乘以价值的贡献来更新运行答案`i`根据配置数量进行加权，使其成为同级别中第一个活跃的最低配置。 
4.然后我们增加`remaining`经过`m_i`，因为这些元素现在是可用于未来（较小）值的构造后缀的一部分。 

处理完所有值后，累加总和给出最终答案。 

### 为什么它有效

 核心不变量是处理后的值大于`i`，这些值的所有有效部分排列都统一表示为`ways`，并且每个配置都有相同的组合权重。 当我们插入值时`i`，我们正在枚举所有交错`i`到这些配置中，二项式系数考虑了所有可能的位置，而无需重复计算。 由于前缀最小值仅取决于值的降序相对顺序，因此每次引入较小的值时，我们都会正确识别它是否成为最小链的一部分，并且每个有效排列对累积加权和仅贡献一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    
    # constraints across tests
    maxN = 10**6
    maxM = 10**7
    
    # precompute factorials once
    # since sum over tests is large, we allocate up to max total size
    N = 10**6 + 5
    
    fact = [1] * (N)
    inv = [1] * (N)
    invfact = [1] * (N)
    
    for i in range(2, N):
        fact[i] = fact[i - 1] * i % MOD
    
    inv[1] = 1
    for i in range(2, N):
        inv[i] = MOD - MOD // i * inv[MOD % i] % MOD
    
    for i in range(2, N):
        invfact[i] = invfact[i - 1] * inv[i] % MOD
    
    for _ in range(t):
        n = int(input())
        m = list(map(int, input().split()))
        
        total = sum(m)
        
        ways = 1
        rem = 0
        ans = 0
        
        for i in range(n, 0, -1):
            c = m[i - 1]
            if c == 0:
                continue
            
            ways = ways * fact[rem + c] % MOD
            ways = ways * invfact[rem] % MOD
            ways = ways * invfact[c] % MOD
            
            ans = (ans + ways * i) % MOD
            
            rem += c
        
        print(ans % MOD)

if __name__ == "__main__":
    solve()
```阶乘预计算可以通过逆阶乘快速计算二项式系数。 DP 循环维护放置所有当前处理的元素的方式数量。 每个步骤都使用多项式展开逻辑将当前值块插入到现有排列中。 

更新内容`ways = ways * C(rem + c, c)`通过阶乘比率实现，确保我们计算新值组与先前放置的元素的所有交错。 答案不断累积`i * ways`因为每个值`i`充当所有有效安排中潜在的新前缀最小边界。 

一个常见的陷阱是更新`rem`在计算贡献之前，这会错误地移动组合边界。 顺序很重要，因为`ways`必须表示插入当前块之前的配置。

 ## 边缘情况

 一个关键的边缘情况是当所有质量都集中在大指数时，例如`m[n] = 10^7`和所有其他零。 在这种情况下，只有一个值起作用，答案应减少为`n * 1`，因为每个排列都有相同的前缀最小结构。 

另一种边缘情况是所有值的频率都相等。 该算法必须正确考虑所有排列`(n!)`同时对每个可能的最小值的贡献进行加权。 多项式更新确保每个排列都被精确计算一次`ways`。 

第三种情况是稀疏分布，其中指数存在较大差距。 反向扫描会跳过零计数值，正确性依赖于不更新`ways`不必要的。 这确保我们不会引入幻象组合状态。 

最后一个边缘情况是处理非常大的总和`m_i`。 阶乘数组的大小必须根据总和而不是`n`，否则二项式系数将悄悄溢出或变得不正确。
