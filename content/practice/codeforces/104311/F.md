 ## 解决方案
 ## 问题理解

 我们给定两个相同大小的二进制网格，称它们为起始网格和目标网格。 唯一允许的移动是选择一个连续的长度段`l`在行内水平或在列内垂直，并翻转该段中的所有位。 翻转的意思是把0变成1，把1变成0。 

问题是，在任意次数的此类段翻转之后，是否有可能将起始网格精确地转换为目标网格。 

关键的困难在于操作重叠和交互。 单元不是独立可控的，因为翻转一个段会同时影响多个位置，并且多个段可以重叠在同一单元上，从而取消或加强翻转。 

约束允许最多 100 个测试用例，所有测试的单元总数最多为 1000 个。这个值足够小，以至于每个测试都需要线性或接近线性，但对于翻转配置的任何指数状态探索来说太大了。 

一种简单的解释是尝试模拟所有可能的操作序列或独立处理每个单元。 两者都会失败，因为操作数量是无限的并且交互是全局的。 

当出现微妙的边缘情况时`l = 1`。 在这种情况下，每个操作都会翻转一个单元格，因此任何网格都可以转换为任何其他网格。 假设邻居之间存在交互的粗心解决方案可能会错误地拒绝这种情况。 

另一个边缘情况是当`l = n`或者`l = m`。 然后每个操作变成一个完整的列或完整的行翻转段，将问题减少到每行或每列的全局奇偶校验约束。 将其视为局部传播问题将会失败。 

## 方法

 强力视角将每个允许的段视为切换单元子集的操作。 我们可以想象构建一个图，其中每个状态都是完整的网格配置，边代表有效的翻转。 状态数为`2^(n*m)`，尽管每个状态都有很多转换，但探索这个图是完全不可行的。 

即使我们限制自己对每个单元进行推理，我们仍然面临依赖性：翻转一个段会影响多个单元，而这些单元会影响未来的有效操作。 任何模拟翻转序列的尝试都会遭遇指数爆炸。 

关键的观察结果是翻转的行为类似于二进制字段上的异或运算。 每个操作都会切换固定模式，以任何顺序应用操作相当于选择其 XOR 与差异网格匹配的操作子集`a XOR b`。 

这将问题转化为确定差异网格是否可以表示为允许段的线性组合（在 GF(2) 上）。 段的结构形成了一个高度规则的系统，我们可以贪婪地处理网格，从左上角到右下角传播所需的翻转，而不是推理全局组合。 

关键思想是，一旦我们决定是否应用从某个位置开始的段，其效果仅影响其范围内的单元格，并且我们可以逐行、逐列强制一致性。 

我们将问题简化为检查是否可以通过按确定性顺序贪婪地修复所有差异来消除所有差异，确保每次强制翻转在范围内有效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力操作 | O(2^(nm)) | O(2^(nm)) | O(纳米) | 太慢了|
 | 网格上的线性传播 | O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 我们首先计算差异网格`d`， 在哪里`d[i][j] = a[i][j] XOR b[i][j]`。 目标是消灭所有`d`使用允许的段翻转。 

我们从左上角到右下角处理网格，保持这样的想法：当我们到达一个单元格时，所有可能影响较早单元格的操作都已经决定了。 

1. 对于每个单元格`(i, j)`， 如果`d[i][j] == 0`，我们什么也不做并继续。 
2.如果`d[i][j] == 1`，我们必须使用覆盖该单元格的有效操作来修复它。 我们有两个候选：一个水平线段，起始于`(i, j)`如果`j + l <= m`，或开始于的垂直线段`(i, j)`如果`i + l <= n`。 
3. 如果两个段都不适合，我们无法修复此单元格并立即返回“NO”。 这是因为以后的操作不会影响`(i, j)`也不违反已经处理的约束。 
4. 如果水平线段有效，我们通过翻转所有水平线段来应用它`d[i][j .. j+l-1]`。 
5. 否则，我们通过翻转所有应用垂直线段`d[i .. i+l-1][j]`。 
6. 继续，直到处理完所有细胞。 

顺序很重要，因为我们总是解决最早的未解决的单元格。 这确保了以后的操作不会使网格的先前固定前缀无效。 

### 为什么它有效

 每个操作都会翻转一个连接的块，但每个单元首先在扫描顺序中唯一的最早位置遇到。 此时，解决差异的唯一方法是选择锚定在该单元格的段，因为任何较晚开始的段都无法覆盖它，而任何较早开始的段都已经被决定了。 

这强制了贪婪的唯一性属性：第一次单元需要校正时，我们最多有两个确定性选择，要么导致一致的扩展，要么不存在解决方案。 XOR 结构确保以这种贪婪顺序应用操作不需要回溯，因为翻转两次会取消并且所有效果都是线性的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, l = map(int, input().split())
        a = [list(map(int, input().split())) for _ in range(n)]
        b = [list(map(int, input().split())) for _ in range(n)]

        d = [[a[i][j] ^ b[i][j] for j in range(m)] for i in range(n)]

        ok = True

        for i in range(n):
            for j in range(m):
                if d[i][j] == 0:
                    continue

                # try horizontal
                if j + l <= m:
                    for k in range(j, j + l):
                        d[i][k] ^= 1
                elif i + l <= n:
                    for k in range(i, i + l):
                        d[k][j] ^= 1
                else:
                    ok = False
                    break

            if not ok:
                break

        print("YES" if ok and all(all(row == 0 for row in d[i]) for i in range(n)) else "NO")

if __name__ == "__main__":
    solve()
```该解决方案构建差异网格并在遇到差异网格时贪婪地清除它们。 如果可能，水平翻转是首选，但只要它覆盖当前单元格，任何一种选择都是有效的。 最终验证确保不存在任何残留差异。 

一个微妙的点是我们必须立即完全应用段翻转。 延迟更新或尝试计算奇偶校验而不是更新网格会破坏正确性，因为未来的决策取决于更新的状态。 

最后的全网格检查是必要的，因为当检测到强制故障时可能会发生提前终止，但部分处理仍可能留下非零条目。

 ## 边缘情况

 当`l = 1`，每个操作恰好翻转一个单元格。 该算法正确地将每个差异视为可局部修复，因为水平或垂直段始终存在长度为 1。因此，任何网格都可以转换为任何其他网格，并且贪婪循环减少为独立地清除每个单元格。 

什么时候`l`等于整个宽度或高度，翻转跨越整个行或列段。 该算法可以自然地处理这一问题，因为每个单元只有一个方向可用，从而强制传播一致。 如果不匹配出现在没有长度段的位置`l`适合，算法立即正确拒绝。 

当差异集中在边界附近时，例如最后一次`l-1`列或行，算法可能会遇到无法被任何有效段覆盖的单元格。 这些案例在处理时就被准确地检测到，因为两者`i + l > n`和`j + l > m`失败，产生正确的早期“NO”。
