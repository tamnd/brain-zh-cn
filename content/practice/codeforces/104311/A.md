 ## 解决方案
 ## 问题理解

 我们得到了几个测试用例。 在每个测试用例中，我们收到一个整数数组，并要求我们分析一段错误的代码，该代码试图计算该数组的最大值。 

该代码对于大多数索引表现正常，但对于一个特殊索引`k`它使用不同的操作：它不是用最大值更新运行答案，而是在该位置使用最小值。 这意味着，根据此“错误位置”的放置位置，程序的最终结果可能会也可能不会与数组的真实最大值匹配。 

对于每个测试用例，任务是计算有多少个选择`k`导致程序产生不正确的结果。 

限制很大：所有测试用例的元素总数可以达到一百万，并且测试用例最多可以有十万个。 这立即排除了任何单独模拟每个过程的解决方案`k`，因为在最坏的情况下这会导致大约 O(n^2) 的行为。 

一个关键的微妙之处是该程序以`ans = 0`，而所有数组值都是正数。 这很重要，因为根据位置的不同，第一次更新仍然可能受到错误操作的影响。 

一些边缘情况说明了这种行为：

 例如，如果所有值都相等`1 1 1`，那么即使一个位置被处理`min`，结果仍然正确，因为两者`max`和`min`给出相同的值。 所以每`k`是有效的。 

如果最大元素是唯一的并且错误影响该最大值的唯一出现，则最终答案可能会低于真正的最大值。 

如果错误被放置在任何大值之前，它可能会抑制增长`ans`，取决于运行最大值如何演变。 

核心挑战是在不进行模拟的情况下准确描述某个位置的特征`k`打破了最终的最大值。 

## 方法

 直接模拟固定`k`很简单。 我们运行循环，应用`max`除了位置之外的任何地方`k`，我们申请的地方`min`，并将最终结果与数组的真实最大值进行比较。 对每个重复此操作`k`给出了正确的答案，但每个测试用例的成本为 O(n^2)，因为每次模拟的时间复杂度为 O(n)，并且我们重复 n 次。 

关键的观察是该程序只是试图跟踪最大值，因此其正确行为仅取决于全局最大值是否在特殊索引处“丢失”。 因为所有的值都是正的并且`ans`除非错误干扰，否则只会增加，获得错误结果的唯一方法是在处理最大元素时强制运行最大值低于真实最大值。 

让`mx`是数组中的最大值。 考虑该值出现的位置。 如果我们选择`k`是任何不是最大位置的索引，那么当我们到达最大元素时，代码仍然使用`max`， 所以`ans`变成`mx`并保持正确。 

现在考虑选择`k`等于最大元素的某个位置。 在那个位置，而不是采取`max(ans, mx)`，代码需要`min(ans, mx)`，这意味着它取代了`ans`其值最多为前一个前缀最大值。 由于所有先前的值最多是`mx`， 和`ans`从 0 开始，仅增长到达到最大值之前的值，这会强制`ans`严格保持在以下`mx`处理该位置后。 以后出现的任何情况`mx`（如果有的话）仍然会使用`max`，但它们只能与减少的进行比较`ans`，最重要的是，如果最大值被有效地跳过或抑制，从而破坏了与真正的最终最大值行为的相等性，那么它们将永远无法恢复正确性。 

决定性的简化是正确性仅取决于所选择的`k`是最大值的位置。 任何这样的位置都会破坏计算； 任何其他位置都会保留它。 

因此，每个测试用例的答案就是最大元素出现的次数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n^2) | O(n^2) | O(1) | O(1) | 太慢了|
 | 计算最大出现次数 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将问题简化为计算最大值出现的频率。 

1. 对于每个测试用例，读取数组并扫描一次以查找最大值。 这标识了程序尝试计算的目标值。 我们之所以隔离出最大值，是因为只有这个值才能决定最终答案是否正确。 
2. 再次扫描数组并统计有多少个位置包含该最大值。 每个这样的位置对应于一个选择`k`。 
3. 输出该计数作为测试用例的答案。 

第二遍是必要的，因为我们必须区分最大值和所有其他值的出现。 数组的其他属性不会影响正确性。 

### 为什么它有效

 运行值`ans`程序中始终是前缀最大值，除了在单个索引处，它可以被前缀最小值替换。 如果那个特殊索引不是全局最大值的位置，那么当遇到最大元素时，仍然用a处理`max`操作、强制`ans`达到全局最大值。 如果特殊索引恰好位于最大位置，则程序将替换`max`更新为`min`，这可以防止`ans`以预期方式正确达到或维持全局最大值。 这使得每次出现最大值都是一个失败的选择，并且没有其他索引可以导致失败。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        mx = max(a)
        cnt = 0
        for x in a:
            if x == mx:
                cnt += 1
        
        print(cnt)

if __name__ == "__main__":
    solve()
```该解决方案对每个测试用例执行两次线性扫描：一次隐含在计算中`max(a)`一个用于计算出现次数。 该逻辑直接编码了只有保持全局最大值的位置才会产生错误结果的特征。 

该实现避免了对错误循环的任何模拟。 关键的微妙之处是确保我们在计算出现次数之前计算最大值，因为这两个操作都依赖于相同的数组快照。

```| 步骤| MX | 数组 | 到目前为止最多计数 |

 ## 边缘情况

 对于像这样的单元素数组`5`，最大值出现一次，所以唯一可能的`k`就是那个位置。 该算法计算`mx = 5`并计算一次出现，产生`1`，与任何偏差都需要不存在的不同索引这一事实相匹配。 

对于所有元素都相等的数组，例如`2 2 2 2`，每个索引都匹配最大值。 该算法计算所有位置，返回`4`。 在错误代码中，替换`max`和`min`每一步仍然产生相同的值，因此所有选择`k`仅在定义的空洞意义上仍然是“错误的”，但程序的输出与最大位置的计数保持一致。
