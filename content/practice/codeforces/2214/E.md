 ## 解决方案
 ## 问题理解

 我们得到一个最多有一百个顶点的加权无向图。 每条边连接两个编号的节点并具有非负成本。 任务是计算从节点 1 到每个其他节点的最小可能距离，其中距离表示沿所选路径的边权重之和。 

输入可以解释为由道路连接的城市网络以及出行成本。 从城市 1 开始，我们想知道到达其他所有城市的最便宜的方式，或者确定根本无法到达某个城市。 

约束足够小，经典的最短路径方法就足够了。 最多 100 个节点，邻接矩阵或邻接列表都可以轻松满足。 在最坏的情况下，边的数量可以达到大约 5000 条，因此任何具有大致二次或稍微超二次行为的解决方案仍然可以快速运行。 这立即排除了对路径的任何指数搜索，但更重要的是，它使带有二进制堆的标准 Dijkstra 足够快。 

当某些节点与节点 1 断开连接时，会出现微妙的边缘情况。在这种情况下，正确的输出是 -1，而不是 0 或无穷大或较大的哨兵值。 

另一个重要的极端情况是零权重边缘。 由于权重可以为零，任何依赖于简单 BFS 或假设严格正权重的算法都会失败。 例如，如果我们有一条像 1-2 (0)、2-3 (5) 这样的链，那么节点 3 可以以成本 5 到达，但朴素的 BFS 会错误地平等对待所有边。 

第三个问题是由同一对节点之间的多个边引起的。 由于图在输入解释中不能保证简单，因此如果不小心实现覆盖邻接条目而不是保留最小权重边，可能会错误地增加距离。 

## 方法

 强力的想法是尝试从节点 1 到每个其他节点的所有可能路径，并跟踪遇到的最小成本。 从概念上讲，这是正确的，因为它探索了图中游走的整个搜索空间。 然而，路径的数量呈指数增长。 即使在具有适度分支因子的图中，长度达到 n 的不同游走的数量也可能会爆炸超出任何可行的限制。 这在密集图中尤其明显，其中每个节点都连接到许多其他节点，并且重新访问状态会创建无界的组合扩展。 

关键的结构观察是，一旦我们知道到节点的最短距离，我们就不需要重新考虑到达它的更长的方法。 这种单调的“最终确定”属性成立，因为所有边权重都是非负的。 它允许我们从当前最近的未到达节点开始贪婪地扩展，始终以递增的顺序锁定最佳距离。 这正是 Dijkstra 算法适用的设置。 

改进来自于用局部松弛代替全局路径枚举。 我们没有探索完整路径，而是使用留下已到达节点的边来反复改进已知距离，始终优先考虑最小的暂定距离。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力路径| 指数| O(n) 递归 | 太慢了|
 | Dijkstra（堆）| O(m log n) | O(n + m) | 已接受 |

 ## 算法演练

1. 构建一个邻接列表，其中每个节点存储成对的邻居和边权重。 这种表示是必要的，因为我们在松弛期间有效地重复遍历出边。 
2. 为除节点 1 之外的所有节点初始化一个无穷大的距离数组，节点 1 被设置为 0。这编码了这样一个事实：我们从节点 1 开始，没有任何成本。 
3. 将 (0, 1) 对推入优先级队列。 队列始终存储按当前已知最短距离排序的候选状态。 
4. 反复从队列中提取暂定距离最小的节点。 该节点表示当前知识下最接近的尚未最终确定的顶点。 
5. 如果提取的距离大于该节点存储的距离，则跳过它。 发生这种情况是因为已经找到了更好的路径并稍后将其推入队列。 
6. 对于当前节点的每个邻居，计算通过该节点的候选距离。 如果它改善了存储的距离，则更新它并将新的对推送到优先级队列中。 
7. 继续，直到优先级队列为空，这意味着所有可达节点都已按距离递增顺序处理。 
8. 输出节点 2 到 n 的最终距离，用 -1 替换不可到达的节点（仍然无穷大）。 

步骤 5 之所以重要是因为同一个节点可能会在距离过时的队列中多次出现。 如果不跳过陈旧的条目，我们将错误地使用次优值来放松边缘并显着增加运行时间。 

### 为什么它有效

 每时每刻，当一个距离为d的节点从优先级队列中弹出时，我们声称d是从节点1到该节点的最小可能距离。 这是成立的，因为所有边权重都是非负的，因此稍后到达该节点的任何替代路径必须累积至少与当前发现的最佳路径一样多的成本。 因此，一旦一个节点被弹出，它的距离就被最终确定，并且永远不会得到改善。 这个不变量确保所有松弛向外传播正确的最小距离。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        adj[u].append((v, w))
        adj[v].append((u, w))
    
    INF = 10**18
    dist = [INF] * (n + 1)
    dist[1] = 0
    
    pq = [(0, 1)]
    
    while pq:
        d, u = heapq.heappop(pq)
        
        if d != dist[u]:
            continue
        
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    
    for i in range(2, n + 1):
        if dist[i] == INF:
            print(-1)
        else:
            print(dist[i])

if __name__ == "__main__":
    solve()
```邻接表构造确保每个无向边在两个方向上都可用。 距离数组用一个大哨兵来初始化，以表示未知的最短路径。 优先级队列总是扩展当前最知名的前沿节点。 

陈旧条目检查`if d != dist[u]`防止过时的队列条目触发不必要的放松。 这是在重复更新下保持 Dijkstra 高效的标准优化。 

最后，不可到达的节点保持无穷大并在输出中转换为 -1。

 ## 边缘情况

 断开连接的节点场景显示了如何保留无穷大。 考虑：```
3 1
1 2 5
```永远无法到达节点 3。 该算法从不将其推入队列，因此其距离保持为 INF 并打印为 -1。 

零权重边缘情况：```
3 2
1 2 0
2 3 5
```最初 dist[2] 变为 0。当处理节点 2 时，它以成本 5 将边放宽到 3。最终结果正确地反映了允许零成本遍历，而不违反 Dijkstra 的排序。 

多重边缘情况：```
3 3
1 2 10
1 2 1
2 3 1
```第二条边将 dist[2] 改进为 1，并且所有后续松弛都使用此改进值，即使输入包含冗余或主导边，也能确保正确性。
