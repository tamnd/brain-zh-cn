 ## 解决方案
 ## 问题理解

 我们正在模拟一个沿整数线移动的一维机器人。 机器人从指定位置开始$x$，可以为负或正，但最初绝不为零。 给出了长度固定的命令序列$n$，其中每个命令将其向左或向右恰好移动一个单位。 

机器人按顺序执行命令，每秒一个。 重要的变化是，每当它到达位置零时，执行指针就会重置回序列的第一个命令，并且机器人从那里再次继续。 如果它完成整个命令序列而不为零，则该过程完全停止。 

任务不是直接模拟仓位$k$秒，因为$k$可以非常大，而是计算机器人在该时间窗口内准确落在零上的次数。 

这些限制立即排除了简单的模拟。 直接的逐步模拟是$O(k)$，并且自从$k$可以达到$10^{18}$，即使是单个测试用例也是不可能的。 相反，该解决方案必须按照命令序列的循环来工作。 

一个微妙的困难是，该过程不是以简单的方式周期性的，因为重置取决于达到零，而不是完成序列。 

一些边缘案例凸显了天真的推理失败的原因。 首先，考虑一个从某个起始位置永远不会达到零的序列。 在这种情况下，机器人可能会提前完成序列并停止，因此计数周期会被高估。 

其次，考虑机器人在一次通过中多次到达零的序列。 每次这样的命中都会重置执行，这意味着在这些情况下我们实际上从未完成完整的序列，并且根据完整运行进行的推理变得无效。 

第三，无论第一次命中发生得早还是晚，起始位置的负数或正数都会发生变化，因此我们不能在不跟踪前缀行为的情况下假设对称性。 

## 方法

 强力模拟实际上每秒执行一个命令，更新位置，递减$k$，并在达到零时重置指令指针。 这是正确的，但每次重置都会使我们回到序列的开头，并且在最坏的情况下，我们可能会重复遍历字符串的前缀。 和$k$最多$10^{18}$，这种做法是完全不可行的。 

关键的观察是该过程完全由两个状态决定：命令字符串中的当前位置和当前索引。 然而，随着时间的推移跟踪所有可能的状态是不必要的。 相反，我们只关心从给定状态开始达到零需要多长时间，以及重置后立即发生的情况。 

从序列开头的固定起始位置开始，我们可以预先计算机器人何时首次到达零。 如果在耗尽序列之前它从未达到零，则该过程立即结束。 否则，假设第一次达到零是在步骤$t$。 然后我们就消费了$t$秒并获得一次重置事件。 重置后，机器人在零位置重新启动，并再次执行完整序列。 

这将问题简化为两个阶段。 首先，计算第一次从$x$当我们达到零时。 其次，当我们在运行序列时再次达到零时，计算从零开始的第一次时间。 第二阶段成为循环发生器：一旦为零，每次我们返回零时，我们都会以相同的方式重新启动，因此该模式会重复。 

因此，该解决方案简化为使用前缀模拟计算两个值：

 一个是第一次点击时间$x$，另一个是第一次归零时间$0$。 之后，我们要么得到零次出现、一次出现，要么使用算术得到重复的循环计数$k$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟|$O(k)$|$O(1)$| 太慢了|
 | 前缀+循环分析|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们首先将命令字符串转换为前缀位移数组，以便我们可以快速计算位置。 

1. 计算命令序列的前缀位移，其中每个L贡献-1，每个R贡献+1。 这让我们知道序列任何前缀之后的位置，而无需模拟开销。 
2. 从初始位置开始$x$，扫描前缀和并找到最早的索引$i$这样$x + prefix[i] = 0$。 这代表机器人第一次运行时达到零的时刻。 
3. 如果不存在这样的索引$n$步骤，机器人永远不会重置，只会执行直到完成或时间到$k$耗尽。 在这种情况下，答案是 0 或 1，具体取决于起始路径是否为零，但由于没有发生重置，我们只是在第一次运行结束后停止计数。 
4. 如果第一次命中发生在某个时间$t_1$，我们将答案增加 1 并减少$k$经过$t_1$。 系统现在使用完整的命令序列从位置零重新启动。 
5. 现在从位置零开始模拟并再次找到第一次$t_2$使得前缀达到零。 如果没有这样的$t_2$存在，不会发生进一步的重置，因此我们返回当前答案。 
6. 如果有这样一个$t_2$存在，那么每一个$t_2$几秒钟后我们再次重置。 我们添加$\lfloor k / t_2 \rfloor$到答案并完成。 

这种减少有效的原因是，一旦机器人归零，复位后的状态每次都是相同的：相同的起始位置、相同的指令指针和相同的序列。 这使得未来的行为具有固定周期的周期性$t_2$，所以计数就变成了一个简单的除法问题。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x, k = map(int, input().split())
        s = input().strip()

        # prefix displacement
        pref = []
        cur = 0
        first_hit_from_x = -1

        for i, c in enumerate(s):
            if c == 'L':
                cur -= 1
            else:
                cur += 1
            pref.append(cur)

            if first_hit_from_x == -1 and x + cur == 0:
                first_hit_from_x = i + 1

        if first_hit_from_x == -1 or first_hit_from_x > k:
            print(0)
            continue

        # first reset
        ans = 1
        k -= first_hit_from_x

        # now start from 0
        cycle = -1
        for i, v in enumerate(pref):
            if v == 0:
                cycle = i + 1
                break

        if cycle == -1:
            print(ans)
            continue

        ans += k // cycle
        print(ans)

if __name__ == "__main__":
    solve()
```该实现依赖于前缀位移以避免重复模拟。 变量`cur`在命令字符串的每个前缀之后保持净移动。 这让我们可以在每步的恒定时间内检查零的可达性。 

第一个循环计算前缀数组和机器人从以下位置开始达到零的最早时间$x$。 这很重要，因为由于非零开始，第一个段的行为与所有后续段的行为不同。 

第一次重置后，系统始终从零位置重新启动。 这就是为什么第二个循环仅检查前缀本身何时变为零，而不添加$x$。 

一个微妙的点是我们只计算剩余时间内的完全重置。 如果剩余时间小于循环长度，整数除法自然可以正确处理部分循环。

### 示例 1

```前缀值：

 | 2 | 左 | 0 | 是的 |
 | 3 | 右 | 1 | 不相关|

 第一次命中发生在时间 2，因此会发生一次重置并且$k = 4$。 

现在从零开始：

 | 步骤| 前缀 | 打零 |
 | --- | --- | --- |
 | 1 | -1 | 没有|
 | 2 | -2 | 没有|
 | 3 | -1 | 没有|

 没有进一步达到零，所以答案仍然是 1。 

这演示了只有初始段起作用的情况。 

### 示例 2

 输入：```
2 -1 8
RL
```从$x=-1$：

 | 步骤| 移动| 位置|
 | --- | --- | --- |
 | 1 | 右 | 0 |
 | 2 | 左 | -1 |

 我们在第 1 步中达到了 0，因此重置了 1。 

从零开始：

 | 步骤| 前缀 | 位置|
 | --- | --- | --- |
 | 1 | 1 | 1 |
 | 2 | 0 | 0 |

 循环长度为 2，因此消耗 8 秒后，我们总共获得 4 次命中。 

这显示了第一次重置后的周期结构。

 ## 边缘情况

 一个关键的边缘情况是机器人即使从起始位置也永远不会到达零。 在这种情况下，第一个循环永远找不到有效的前缀，因此答案立即为零。 例如，如果$x=3$并且序列仅向右移动，不会发生重置并且执行提前结束。 

另一种情况是机器人在第一次部分运行期间到达零，但再也没有从零开始。 在这种情况下，我们只计算一次重置。 该算法处理这个问题是因为`cycle`保持-1，防止分裂。 

第三种情况是当循环长度为1时，这意味着前缀立即从零一步返回到零。 该算法正确地将剩余的每一秒计数为重置，因为整数除以 1 会累加所有剩余时间。 

这些案例证实了首次命中逻辑和循环压缩在简并命令模式中的行为正确。
