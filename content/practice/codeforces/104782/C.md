 ## 解决方案
 ## 问题理解

 我们被要求仅使用两种类型的篮球投掷来构建目标得分：一种类型加 2 分，另一种类型加 3 分。 给定一个整数`n`，我们需要确定是否可以精确地形成`n`使用这些投掷的某种组合来得分。 如果可能的话，我们还必须尽量减少抛出的总数。 在所有有效组合中，我们必须输出使用了多少个 2 分球和多少个 3 分球。 

输入是单个整数`n`，代表我们想要达到的确切分数。 输出是一对`(a, b)`意义`a`投掷 2 分并`b`投掷 3 分完全达到`n`，并且此组合使用尽可能少的总抛出次数，或字符串`No`如果不存在这样的组合。 

约束条件`n ≤ 10^9`立即排除任何试图以幼稚的方式迭代所有可能的抛出次数的解决方案。 在最坏的情况下，即使对 2 分和 3 分投掷的可能计数进行双循环也会太慢，因为可能性的数量随着`n`。 

当较小的值时会出现微妙的边缘情况`n`无法准确形成。 例如，`n = 1`显然不能表示为`2a + 3b`，所以正确的输出是`No`。 相似地，`n = 2`工作原理很简单`(1, 0)`， 和`n = 3`作为`(0, 1)`。 另一个不明显的问题是，像“尽可能多地使用三分球”这样的贪婪选择可能无法给出最少的投掷次数，甚至无法达到目标，即使存在有效的表示。 

## 方法

 暴力方法会尝试所有对`(a, b)`这样`2a + 3b = n`。 对于每个可能的值`a`从`0`到`n // 2`，我们检查是否`(n - 2a)`可以整除`3`。 如果是这样，我们计算`b = (n - 2a) / 3`并用最少的时间跟踪解决方案`a + b`。 

这是正确的，因为它明确枚举了每个有效的分解。 然而，它需要迭代到`O(n)`的值`a`，并且对于每一个我们都不断地工作。 和`n`最多`10^9`，这变得完全不可行。 

关键的观察结果是，最小化投掷次数意味着最大化 3 分球投掷次数，因为每次 3 分球投掷比 2 分球投掷在每次操作中获得更多分数。 但我们也不能盲目地采取`n // 3`为三分球投掷次数，因为平价限制可能会强制进行调整。 具体来说，选择后`b`, 剩余值`n - 3b`必须是均匀的。 

这将问题转化为寻找最大可行的`b`这样`n - 3b ≥ 0`和`n - 3b`可以整除`2`。 一旦有这样一个`b`被发现，`a`被唯一确定为`(n - 3b) / 2`。 

我们只需要检查最多几个候选人`n // 3`，因为减少`b`1 将余数改变 3，从而翻转奇偶校验。 这保证了我们能够快速找到有效的解决方案（如果存在）。

 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们想要构建`n`在保持有效性的同时，尽可能多地投三分球。 

1. 计算最大可能的三分球投掷次数为`b = n // 3`。 这给出了三分球的最大得分贡献，但不超过`n`。 剩余的分数将通过 2 分掷球来处理。 
2. 虽然`b`为非负数，检查剩余分数是否`n - 3b`可被 2 整除。如果是，我们就找到了有效的分解。 此条件确保可以使用 2 分球准确形成剩余球。 
3. 如果余数不能被 2 整除，则减少`b`减 1，然后重试。 减少`b`将剩余值恰好改变 3 个点，从而切换奇偶性，因此最多经过少量调整后就会出现有效的解决方案。 
4. 如果我们找到这样一个`b`, 计算`a = (n - 3b) // 2`和输出`(a, b)`。 
5. 如果我们减少`b`低于零而没有找到有效的配置，输出`No`。 

### 为什么它有效

 每个有效解对应一个整数对`(a, b)`满足线性丢番图方程`2a + 3b = n`。 在所有这些对中，最小化抛出次数相当于最大化`b`，因为用 2 分球代替 3 分球总是会增加投球总数。 

从尽可能大的开始`b`仅在必要时减少，我们确保永远不会跳过更好的解决方案。 奇偶条件`n - 3b ≡ 0 (mod 2)`一次充分表征可行性`b`是固定的，因此检查连续值`b`保证正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())

    b = n // 3
    while b >= 0:
        rem = n - 3 * b
        if rem % 2 == 0:
            a = rem // 2
            print(a, b)
            return
        b -= 1

    print("No")

if __name__ == "__main__":
    solve()
```该代码遵循前面描述的贪婪结构。 我们从最大可能的三分球投掷次数开始，只有当剩余的次数无法用两分球投掷来表示时才向下调整。 关键的实现细节是计算`rem = n - 3 * b`并在除法之前检查奇偶校验，这可以避免浮点或无效的整数除法。 

循环是安全的，因为它最多运行`n // 3`理论上来说，但实际上由于奇偶校验交替，只需要恒定次数的迭代。

 ## 边缘情况

 对于`n = 1`，算法开始于`b = 0`，给出余数`1`。 自从`1 % 2 != 0`，它减少`b`到`-1`并停止，正确输出`No`。 这与 2 和 3 的组合不能形成 1 的事实相符。 

对于`n = 2`，我们从`b = 0`，余数为`2`，可以被 2 整除，所以`a = 1`输出是`(1, 0)`。 这证实了该算法可以正确处理纯 2 点结构，而不需要任何 3 点调整。 

为了`n = 3`,`b = 1`产生余数`0`，立即给予`(0, 1)`。 这表明，当它们完全适合时，算法会正确地选择更高值的抛出，从而产生最少数量的抛出。
