 ## 解决方案
 ## 问题理解

 我们有一小群人都需要洗澡，但只有一个淋浴可用。 淋浴并不总是可用的：时间被划分为不相交的间隔，期间有水流动，并且每个间隔也有固定的水类型。 在这些时间间隔之外，淋浴不可用。 

每个人都有一个要求：他们只接受特定的水类型，并且每次淋浴需要固定的不间断时间。 一旦一个人进入淋浴间，他们必须在整个时间内不间断地停留，并且在此期间没有其他人可以使用淋浴间。 我们的目标是按某种顺序安排所有人进入可用的水间隔，以便每个人都能尽早完成，并且我们希望最后一个人完成时的时间尽可能短。 

关键的结构是，我们将固定长度的任务打包到具有“有效片段”的时间线中，其中每个片段都有一个标签（水类型），并且每个人只能被放置在具有兼容标签的片段中。 

这些限制以非常具体的方式发挥作用。 人数最多为 20 人，这足以允许对子集进行指数推理。 然而，淋浴间隔的数量可能高达 100,000，因此任何尝试贪婪地模拟分配或随着时间的推移天真地尝试所有放置的解决方案都会失败。 这立即表明问题的重点部分必须是预处理间隔，以便检查布局的可行性变得更快。 

一个微妙的困难来自于淋浴间隔是固定类型的连续块，并且持续时间很大。 如果一个人在一个区间开始但不完全适应，他们就无法进入下一个区间。 这意味着每个分配都必须严格遵守段边界。 

一个天真的错误是假设我们总是可以“贪婪地按照最早可用时间的顺序排列人们”或“按顺序填充间隔”。 例如，考虑两个人和两个间隔，其中存在一个长间隔，但由于类型限制只有一个人可以使用它。 贪婪策略可能会在短期作业上浪费该时间间隔，并阻止需要长期作业的正确分配。 

当多个间隔具有相同类型但相距较远时，会出现另一种微妙的边缘情况。 即使较早的时间间隔不够，一个人也可能会适应较晚的时间间隔，而跳过这种灵活性会破坏贪婪的排序。 

## 方法

 暴力方法会尝试将每个人分配到一个有效的区间，并选择人员的顺序。 由于有 N 个人，光是排列的数量就是 N 阶乘，即使 N = 20，这也是不可行的。即使我们忽略排序，只尝试子集分配，我们仍然需要考虑与区间容量的兼容性，这取决于连续时间打包。 这将天真的方法推向了探索指数分配与间隔扫描相结合的方式，这太慢了。 

关键的观察结果是 N 非常小，因此我们应该从人员子集的角度进行思考。 我们不是直接决定一个顺序，而是尝试决定哪一组人可以在某个时间T之前完成，然后二分查找答案。 

因此，我们重新表述问题：给定时间 T，我们能否安排所有人员，使他们不晚于 T 完成工作？ 如果我们能够回答这个可行性检查，我们就可以二分查找最小 T。 

现在问题变成了子集上的约束满足问题。 对于固定的 T，每个间隔贡献一个可用时间窗口，但只有一部分可能位于 T 之前。我们需要知道，对于每个间隔，每种类型存在多少可用时间。 然后，必须将每个人分配到一个兼容类型的区间，且不得重叠，同时尊重总容量。

这变成了一个经典的子集 DP/背包式分配问题，其中状态表示哪些人已经被安排以及我们如何消耗区间容量。 

因为 N 最多为 20，所以我们可以使用位掩码来表示人员的子集。 对于固定的 T，我们为每种类型计算可用“槽”的列表（修剪到 T 的间隔）。 然后，我们尝试使用子集上的 DP 将人员分配到这些插槽，我们贪婪地将人员打包到兼容的容量块中。 

关键的简化是每个间隔都是独立的，并且在一个类型中，我们只关心总的可用时间块。 由于类型内部的顺序对于可行性并不重要，因此我们可以将每个间隔视为一个容量箱，并将持续时间适合匹配类型的箱的人员分配给他们。 

因此，可行性简化为检查我们是否可以将所有人员装入按类型分组的垃圾箱中，其中垃圾箱的间隔长度可达 T。 

然后我们二分搜索可以打包的最小 T。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列和区间模拟 | O(N!·M) | O(N!·M) | O(M)| 太慢了|
 | 二分搜索 + 每个类型的子集 DP 打包 | O(log S · 2^N · M 或优化分组) | O(2^N) | O(2^N) | 已接受 |

 ## 算法演练

 1. 首先，将所有区间按水类型分开，并按开始时间排序。 我们将使用它们来计算每种类型在候选时间 T 之前存在多少可用持续时间。 
2. 定义函数`can(T)`检查是否所有人都能在时间 T 之前完成。在这个函数中，我们将每个间隔剪裁为 T 并计算每种类型贡献的可用持续时间。 如果间隔超出 T，则仅计算 T 之前的部分。 
3. 对于每种类型，我们现在都有一个容量块列表。 我们不关心确切的位置，只关心每个块的总可用容量。 
4. 我们考虑按类型分配人员。 对于每个人，我们都知道他们所需的类型和持续时间。 我们按所需类型对人员进行分组。 
5. 对于固定类型，我们尝试将其所有人员分配到其可用容量块中。 这成为一个经典的打包问题，我们必须决定持续时间的总和是否可以划分为具有给定容量的容器。 因为 N 很小，所以我们对该类型的人的子集使用位掩码 DP，跟踪子集是否可以打包到可用的 bin 中。 
6. 如果还有剩余容量，DP 转换会尝试将人员放入当前垃圾箱，或者在需要时移至下一个垃圾箱。 我们探索子集，直到所有的人都挤满了或者没有过渡剩余。 
7. 如果每个类型的组都可以成功打包，则`can(T)`返回真。 
8. 我们在足够大的范围内二分搜索 T，使用`can(T)`引导搜索，并返回最小的可行值。 

正确性取决于间隔是独立资源的事实，并且在每种类型中我们只关心总容量和分段容量。 由于 N 很小，子集 DP 可以正确捕获所有可能的分配，而无需显式构造调度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(T, people, intervals):
    # group intervals by type
    by_type = {-1: [], 0: [], 1: []}
    for s, d, t in intervals:
        if s >= T:
            continue
        end = min(T, s + d)
        if end > s:
            by_type[t].append(end - s)

    # sort capacities per type (greedy packing works better)
    for t in by_type:
        by_type[t].sort(reverse=True)

    # group people by type
    people_by_type = {-1: [], 0: [], 1: []}
    for x, y in people:
        people_by_type[x].append(y)

    # check each type independently
    for t in [-1, 0, 1]:
        req = people_by_type[t]
        if not req:
            continue

        caps = by_type[t]
        if sum(req) > sum(caps):
            return False

        # DP over subset packing into bins
        n = len(req)
        dp = {0: 0}  # mask -> current bin used
        for mask in range(1 << n):
            if mask not in dp:
                continue
            used = dp[mask]
            for i in range(n):
                if mask & (1 << i):
                    continue
                dur = req[i]
                # try same bin
                if used + dur <= caps[-1]:
                    nm = mask | (1 << i)
                    dp[nm] = max(dp.get(nm, 0), used + dur)
                # try next bin
                else:
                    for c in caps:
                        if dur <= c:
                            nm = mask | (1 << i)
                            dp[nm] = max(dp.get(nm, 0), dur)
                            break

        if (1 << n) - 1 not in dp:
            return False

    return True

def solve():
    N, M = map(int, input().split())
    people = [tuple(map(int, input().split())) for _ in range(N)]
    intervals = [tuple(map(int, input().split())) for _ in range(M)]

    lo, hi = 0, 10**18
    ans = hi

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, people, intervals):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先将可行性包装到二分搜索中。 这`can(T)`函数将所有淋浴间隔压缩为时间 T 之前的可用容量，按水类型分隔。 这避免了显式模拟时间并减少了资源分配的问题。 

在每种类型中，我们将问题简化为将人员装入容量块中。 位掩码上的 DP 确保我们在不固定顺序的情况下探索分配的所有子集，这是至关重要的，因为不同的顺序会导致不同的 bin 使用模式。 

二分搜索结构确保我们不会直接猜测答案，因为可行性在 T 中是单调的。

 ## 边缘情况

 一种微妙的边缘情况是，一个人完全适合垃圾箱的剩余碎片。 如果实现仅检查严格的不平等，它将错误地拒绝有效的展示位置。 在 DP 中，这是通过允许`used + dur <= capacity`，确保接受精确配合。 

另一种情况是总容量足够，但跨仓的碎片不正确。 例如，一个人需要 10 个单位，我们有大小为 6 和 6 的箱子。贪心求和检查通过，但打包失败。 子集 DP 正确地拒绝了这种情况，因为没有有效的子集分配满足 10 单元的要求。 

第三种情况是多个区间在类型上重叠但在时间上不相交。 该算法独立地对待它们，这是必要的，因为合并它们会错误地假设时间的连续性，而问题并不能保证这一点。
