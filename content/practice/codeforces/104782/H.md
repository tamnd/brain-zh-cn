 ## 解决方案
 ## 问题理解

 我们在无限网格上得到一组点，其中每个点代表一个神经元并用颜色标记。 对于每个查询，我们还会获得一系列颜色。 我们必须构建一系列实际的神经元，每个神经元对应颜色序列中的每个位置，并且我们可以多次重复使用同一个神经元。 

构建序列的成本定义为连续选择的神经元之间的曼哈顿距离之和。 对于查询中的每个位置，我们选择颜色与该位置所需颜色匹配的任何神经元，并且我们希望最大化总路径成本。 

因此，真正的任务是：对于每个查询，给定一个颜色序列，为每个位置选择一个点（从允许的颜色类中），以便使连续所选点之间的曼哈顿距离之和最大化。 

约束足够大，以至于不可能对神经元进行任何每次查询的二次推理。 我们最多可以有 2×10^5 个神经元和最多 2×10^5 个查询，总查询长度最多为 5×10^5。 这已经表明，连续颜色之间的每次转换必须在恒定或对数时间内处理，并且任何涉及直接配对两个颜色类别之间的所有点的操作都太慢。 

一种天真的解释会尝试为查询中的每对相邻颜色计算这两个集合中可能的最佳神经元对。 这个想法在结构上是正确的，但是通过检查所有对来重新计算它的成本太高了。 

当某种颜色在查询中多次出现时，会出现微妙的边缘情况。 由于我们可以重复使用神经元，因此每个位置的选择都是独立的，除非通过邻接。 错误的贪婪解释会尝试在全局范围内为每种颜色选择一个最佳代表并重复使用它，但这会失败，因为最佳选择取决于序列中的两个相邻颜色，而不是全局代表。 

例如，假设一种颜色的点位于 (0,0) 和 (100,0)，另一种颜色的点位于 (0,100) 和 (100,100)。 根据方向，不同的角是最佳的，因此每种颜色的单个固定代表会丢失信息。 

## 方法

 蛮力方法的想法很简单。 对于每个查询以及每个相邻的颜色对，我们尝试来自第一颜色集和第二颜色集的所有神经元对，计算它们的曼哈顿距离，并取最大值。 这是正确的，因为每一步仅取决于两个连续的位置。 但是，如果颜色类有 k 个点，则每次转换成本为 O(k²)，在最坏的情况下，每个查询会退化为 O(n²)，这远远超出了可接受的限制。 

关键的观察是曼哈顿距离有一个结构，可以让我们避免枚举对。 表达式 |x1 − x2| + |y1 − y2| 可以用线性形式重写。 对于任意两点，距离是 (±x ± y) 差异的四种符号配置中的最大值。 这将最大化两个集合之间的曼哈顿距离的问题转化为比较简单投影的极值。 

对于每种颜色，我们不需要保留所有点，而是只需要存储两个变换坐标的极值：x + y 和 x − y。 一旦知道这些，通过比较这些投影的最大值和最小值，计算颜色 A 中的任何点和颜色 B 中的任何点之间的最大曼哈顿距离可以减少到恒定时间。 

这将查询中的每次转换减少到 O(1)，使整个解决方案与总查询大小呈线性关系。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(总查询长度×每种颜色的点数²) | O(n) | 太慢了|
 | 最佳 | O(n + 总查询长度) | O(n) | 已接受 |

 ## 算法演练

 我们首先预处理神经元。

1. 对于每种颜色，我们维护四个值：x + y 的最小值和最大值，以及 x − y 的最小值和最大值。 我们在所有神经元上一次性计算这些。 这将每个颜色类别压缩为恒定大小的信息，保留与极端相关的所有曼哈顿距离行为。 
2. 对于每个查询，我们迭代给定的颜色序列。 
3. 对于每对相邻的颜色 c 和 d，我们使用预先计算的值计算颜色 c 的任何神经元和颜色 d 的任何神经元之间的最佳可能曼哈顿距离。 
4. 为了计算这个过渡值，我们独立评估两个投影。 对于投影 x + y，最佳交叉对来自 max(c) − min(d) 或 max(d) − min(c)。 我们取这两个中的最大值。 我们对 x − y 做同样的事情。 
5. 该转变的答案是两个投影的最大值。 我们将其添加到查询答案中。 
6. 如果查询的长度为 1，则答案为零，因为不存在转换。 

微妙之处在于每个投影都必须考虑两个方向。 最好的配对可能来自任何一方，具体取决于哪一组提供了更大的极端。 

### 为什么它有效

 两点之间的曼哈顿距离可以表示为其坐标的四个线性函数中的最大值。 这意味着在两组点之间，最大可能距离必须由至少在这些线性方向中的一个极端的一对点来实现。 通过仅存储每种颜色的 x + y 和 x − y 的最小值和最大值，我们可以准确保留那些极端候选值。 每个最佳对必须由这些边界值之一表示，因此没有内部点可以改进答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

n = int(input())
mn_sum = {}
mx_sum = {}
mn_diff = {}
mx_diff = {}

for _ in range(n):
    x, y, c = map(int, input().split())
    s = x + y
    d = x - y

    if c not in mn_sum:
        mn_sum[c] = INF
        mx_sum[c] = -INF
        mn_diff[c] = INF
        mx_diff[c] = -INF

    mn_sum[c] = min(mn_sum[c], s)
    mx_sum[c] = max(mx_sum[c], s)
    mn_diff[c] = min(mn_diff[c], d)
    mx_diff[c] = max(mx_diff[c], d)

def best(c, d):
    if c == d:
        return 0

    ans = 0

    ans = max(ans, mx_sum[c] - mn_sum[d])
    ans = max(ans, mx_sum[d] - mn_sum[c])

    ans = max(ans, mx_diff[c] - mn_diff[d])
    ans = max(ans, mx_diff[d] - mn_diff[c])

    return ans

t = int(input())
out = []

for _ in range(t):
    tmp = list(map(int, input().split()))
    m = tmp[0]
    arr = tmp[1:]

    res = 0
    for i in range(m - 1):
        res += best(arr[i], arr[i + 1])

    out.append(str(res))

print("\n".join(out))
```预处理步骤为每种颜色构建四个极值。 每次更新都是恒定时间，因此完整的预处理与神经元数量呈线性关系。 

这`best`函数编码曼哈顿约简。 它显式地检查两个方向，因为最佳配对可能来自任一方向。 自转换情况返回零，因为如果我们重复使用相同的神经元，选择两种相同的颜色不会强制产生距离。 

每个查询都是通过对相邻颜色对之间的转换成本求和来处理的，这与路径成本的分解相匹配。 

一个常见的实施错误是忘记四个方向检查之一或错误地假设对称性。 另一种方法是分别处理 x 和 y 的最小值/最大值，这是不够的，因为曼哈顿距离耦合了坐标。 

## 工作示例

 考虑一个具有两种颜色的小型设置。 

颜色 1 具有点 (0, 0) 和 (10, 0)。 颜色 2 具有点 (0, 5) 和 (10, 5)。 查询是 [1, 2, 1]。 

对于每种颜色，我们计算：

 颜色 1：x+y 为 {0, 10}，x−y 为 {0, 10}

 颜色 2：x+y 为 {5, 15}，x−y 为 {-5, 5}

 现在我们评估转变。 

| 过渡| 最佳 x+y 差异 | 最佳 x−y 差异 | 结果 |
 | --- | --- | --- | --- |
 | 1 → 2 | 最大值(10−5, 15−0) = 15 | 最大值(10−(-5), 5−0) = 15 | 15 | 15
 | 2 → 1 | 最大值(15−0, 10−5) = 15 | 最大值(5−0, 10−(-5)) = 15 | 15 | 15

 总数为 30。 

该跟踪表明，相同的颜色不需要在整个查询中选择一致的点； 每个转变独立地选择极值组合。 

现在考虑单色查询 [1, 1, 1]。 由于每个位置都可以重复使用相同的神经元，因此每个转换的贡献为零。 无论该颜色存在多少个点，输出均为 0。 这证实了自转换正确崩溃。

 ## 边缘情况

 关键的边缘情况是颜色出现在连续位置。 在这种情况下，转换的贡献应始终为零，因为我们可以在两个位置重复使用相同的神经元。 当两种颜色相等时，该算法显式返回零，因此它不会错误地引入距离。 

另一个边缘情况涉及只有一个神经元的颜色。 即使如此，极值结构仍然有效，因为最小值和最大值折叠到相同的值，并且涉及该颜色的所有转换都变得确定性。 该算法自然地处理这个问题，无需初始化之外的特殊外壳。 

最后一个微妙的情况是最佳过渡来自不同方向的不同投影。 该算法可以处理此问题，因为它独立评估 x + y 和 x − y 极值，确保每次转换选择产生最大值的投影。
