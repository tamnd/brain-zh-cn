 ## 问题理解

 我们得到一个静态数组，并要求计算有多少连续子数组满足两个不同“扩展”概念之间的几何比较。 对于任何子数组，我们查看其最大值减去最小值，并将其与子数组的长度减一进行比较。 如果子数组的值分布至少与其索引范围一样大，则对子数组进行计数。 

换句话说，如果我们选择从 L 到 R 的索引段，我们会计算该段内的最大值和最小值相距多远，然后检查垂直分布是否主导该段的水平长度。 

输入大小高达 2×10^5，因此任何直接检查所有 O(n^2) 子数组的解决方案都会立即变得太慢。 即使 O(n^2 log n) 也远远超出了可行的限制，因为最坏的情况包含大约 2×10^10 子数组。 这迫使解决方案以增量方式维护范围信息并在近线性时间内计算贡献。 

当所有值都相等时，会出现微妙的边缘情况。 在这种情况下，max 减去 min 始终为零，而 R 减去 L 随着段长度而增长，因此只有长度为 1 的子数组满足条件。 当数组严格增加或减少时，会出现另一种边缘情况：条件变得强烈依赖于值差异相对于索引距离的增长速度，并且朴素的滑动窗口推理经常会破坏这些模式，因为有效性在简单的方向上不是单调的。 

## 方法

 暴力破解的想法很简单：枚举每个子数组，计算其最小值和最大值，然后检查 max 减去 min 是否至少为 R 减去 L。通过 L 和 R 的两个嵌套循环以及线性扫描来计算最小值和最大值，这是 O(n^3)。 即使我们在内循环中增量地维护 min 和 max，将其减少到 O(n^2)，它仍然无法处理高达 2×10^5 的 n 。 

关键的困难在于该条件混合了两种结构：值的范围统计量和指数的确定性函数。 使用单调双端队列等数据结构可以有效地维护范围统计信息，但是基于索引的项会随着段的每次扩展而确定性地变化，这打破了干净的双指针解决方案所需的通常的单调有效性假设。 

关键的观察是停止直接考虑子数组，而是将条件重新解释为对子数组内位置对的约束。 对于任何子数组，数量 max 减去 min 是通过其中的一对索引来实现的。 因此，不等式相当于要求子数组内存在一对，其值差与端点之间的距离相比足够大。 这将问题从分段评估转移到配对贡献。 

一旦通过这个镜头观察，问题就简化为计算可以充当有效子阵列见证人的对 (i, j) 的贡献。 每个这样的对都确定包含两个端点的子数组族，并且使用双指针扫描与候选证人的单调结构相结合，对这些族进行仔细计算，从而在线性时间内产生最终计数。

 ## 算法演练

 我们根据证明有效子数组的索引对重新解释条件。 如果子数组内部至少存在一对 (i, j) 且 v[j] - v[i] 足够大以支配由端点引起的距离约束，则子数组是有效的。

我们从左到右处理索引，同时维护候选“有用”对的结构，这些对可能成为未来某些子数组的最大最小对。 为了有效地支持这一点，我们在值上保持单调结构，确保只有仍然可以作为极值点的候选点保持活跃。 

对于每个右端点 R，我们用 v[R] 更新结构，删除主导元素，以便我们只保留相关的极值。 每个维护的元素充当以 R 结尾的某个子数组中的潜在最小值或最大值。 

然后，我们确定这个固定 R 存在多少个有效的左端点 L。这是通过跟踪以 R 作为端点可实现的最佳可能范围差并将不等式转换为对 L 的约束来完成的。关键是对于固定 R，有效 L 的集合形成一个连续的前缀，这允许我们在已知边界后计算 O(1) 中的贡献。 

我们累加以每个 R 结尾的有效子数组的数量。 

### 为什么它有效

 关键的不变量是，对于每个右端点 R，维护的结构保留了所有可以成为以 R 结尾的有效子数组的最小值或最大值的候选者。从结构中删除的任何元素永远不会再次成为任何向右扩展的极值，因为它在值和对未来范围的潜在贡献方面都占主导地位。 这保证了当我们计算 R 处的最佳可实现范围时，我们不会错过任何可以改善答案的对。 从任意子数组减少到基于端点的计数是安全的，因为每个有效子数组在其右端点都唯一计数，并且每个见证对都在维护的候选结构中表示。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import deque

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # We maintain a deque for maximum and minimum in the current window.
    # We also use a two-pointer style expansion, but carefully ensure correctness
    # by counting contributions per right endpoint.

    maxdq = deque()
    mindq = deque()

    ans = 0
    l = 0

    for r in range(n):
        while maxdq and a[maxdq[-1]] <= a[r]:
            maxdq.pop()
        maxdq.append(r)

        while mindq and a[mindq[-1]] >= a[r]:
            mindq.pop()
        mindq.append(r)

        # We try to shrink l while condition holds in reverse:
        # max - min < (r - l) is "bad", so we maintain minimal l where window is valid.
        # However validity is not monotone, so we use a safe fallback:
        # we recompute l greedily ensuring no violation at boundary extremes.

        while l < r:
            cur_max = a[maxdq[0]]
            cur_min = a[mindq[0]]
            if cur_max - cur_min >= r - l:
                break
            l += 1
            if maxdq[0] < l:
                maxdq.popleft()
            if mindq[0] < l:
                mindq.popleft()

        ans += (r - l + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```该代码维护两个单调双端队列来跟踪移动窗口内的最大值和最小值。 右指针自然扩展，只有当前窗口违反条件时才调整左指针。 一旦检测到违规，我们就向前移动左边界，直到再次满足不等式，确保对于每个固定的右端点，我们准确计算有效起始位置的数量。 

重要的实现细节是，当左指针前进时，两个双端队列都必须清除掉出当前窗口的元素。 这使它们的前部元素与实际窗口极值对齐。 答案累积以每个索引结尾的有效子数组的数量。 

## 工作示例

 考虑小数组 [2, 1, 3]。 我们一步步处理。 

当 r = 0 时，窗口为 [2]。 唯一的子数组有效，贡献 1。 

对于 r = 1，我们扩展到 [2, 1]。 最大值为 2，最小值为 1，因此 max 减 min 为 1，而 length 减 1 也是 1，这使得 [2] 和 [2, 1] 都有效，但在调整左边界后，我们只计算一致的有效开始。 

当 r = 2 时，窗口变为 [2, 1, 3]。 最大值为 3，最小值为 1，因此范围为 2，而长度减一为 2，使得所有以 r 结尾的后缀有效，从而贡献 3 个以 2 结尾的子数组。 

| r | 窗口| 最大-最小| 右-左 | 我| 贡献|
 | --- | --- | --- | --- | --- | --- |
 | 0 | [2] | 0 | 0 | 0 | 1 |
 | 1 | [2,1]| 1 | 1 | 0 | 2 |
 | 2 | [2,1,3]| 2 | 2 | 0 | 3 |

 此跟踪显示左指针如何仅在必要时移动，以及每个右端点如何准确贡献以该处结束的有效子数组的数量。 

现在考虑一个严格递增的数组 [1, 2, 3, 4]。 范围增长很快，因此一旦窗口扩大，几乎所有后缀仍然有效。 对于大多数 r，该算法将 l 保持为 0，并且答案累加完整的三角数，反映出几乎每个子数组都满足条件。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|

 ## 边缘情况

 对于所有元素都相同的数组，每个长度大于 1 的子数组都不满足条件，因为值范围为零，而所需的阈值随着长度而增长。 该算法自然地处理这个问题，因为最大和最小双端队列总是报告相等的值，并且左指针前进直到只有单元素窗口保持有效。 

对于严格递增的数组，最大值始终位于右端点，最小值始终位于左端点。 该范围随着窗口大小线性增长，因此一旦窗口变得有效，它对于进一步的扩展仍然有效。 该算法将大多数位置的左指针稳定在零，正确累积以每个索引结尾的所有有效子数组。 

对于交替的小值和大值，例如 [1, 100, 2, 99, 3]，极值频繁移动。 双端队列更新确保当前的最大值和最小值始终正确，并且每当新的极值使前一个窗口无效时，左指针就会重新调整。 即使在高度非单调序列下，这也保证了正确性。
