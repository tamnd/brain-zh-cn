 ## 解决方案
 ## 问题理解

 我们有一个矩形网格，其中每个单元格都有一个整数高度。 将此网格视为地形图。 许多人从指定的单元格开始，可以在四个基本方向上每秒移动一步，或者选择保持静止。 

熔岩从高度 0 开始，可以随着时间的推移而上升。 如果在任何时候熔岩水平超过一个人当前站立的牢房的高度，则该人被视为受到伤害。 人们可以在熔岩上升时移动，这样他们就可以在熔岩淹没他们之前尝试到达更高的地方。 

对于从 1 到 n⋅m 的每个目标熔岩级别 L，我们想知道开始升高熔岩之前的最短等待时间，以便可以在不伤害任何人的情况下将其升高到 L 级。 如果给定的 L 是不可能的，则答案为 -1。 

关键的困难在于人不是静态的障碍。 它们可以随着时间的推移重新定位自己，因此安全条件取决于它们的移动速度和地形高度之间的相互作用。 

约束 n、m 高达 700 意味着最多 490,000 个单元。 每个查询的完整基于网格的最短路径计算将太慢。 我们还有多达 10,000 人，因此任何解决方案都必须避免针对每个人每个级别的模拟。 

当一个人从一个被较高单元包围的非常低的单元开始时，就会出现微妙的边缘情况。 即使附近存在高位细胞，如果到达需要时间，除非我们等待足够长的时间，否则低熔岩水平可能仍然是不可能的。 

另一个边缘情况是所有人都从非常高的地形开始。 在这种情况下，即使熔岩高度很大也可能立即可行，从而导致许多 L 值的等待时间为零。 

## 方法

 思考问题的一个直接方法是固定一个熔岩高度L，模拟如果等待t秒后开始升起熔岩，是否所有人都能生存。 对于固定的 t，我们可以模拟运动，同时确保人员在到达时永远不会进入高度低于当前熔岩水平的单元格。 这变成了每 L 和每 t 的时间扩展 BFS 问题，这显然是不可行的。 

简化的关键是反转视角。 我们不是问“我们要等多久才能安全到达 L 级”，而是问“对于每个单元格，至少一个人需要多长时间才能到达 L 级”。 如果某个单元格的高度为 h，那么晚于时间 t 到达该单元格意味着一旦熔岩在时间 t 超过 h，该单元格就不安全。 因此，问题变成了多源最短路径问题，其中源都是人，边代表单位成本的网格移动。 

我们计算任何人到达每个单元格的最短到达时间 dist[i][j]。 一旦我们有了这个，我们就重新解释给定熔岩水平 L 的安全条件。如果单元格的高度低于 L，那么它就是危险的，因为一旦熔岩达到 L，该单元格就会被淹没。 如果在时间 t 时，一个人始终处于高度至少为当前熔岩高度的单元格中，则该人是安全的，这意味着确保他们在时间 t 时可能需要的任何单元格在变得不安全之前都可以到达。 

关键的观察结果是，对于固定的 L，限制因素是任何高度 < L 的单元格在所有人都可以逃离更高地形之前被“封锁”的最早时间。 这变成了按高度排序并受到达时间约束的网格的全局阈值问题。 

我们按照高度递增的顺序处理细胞。 对于阈值 L，在时间 t = dist[i][j] 后，所有高度 < L 的单元都被视为禁止。 保证安全的最早时间 t 是所有高度 < L 最早到达时间的单元中的最大值。 如果任何所需的转义条件失败，则答案为 -1。 

这减少了维护按高度排序的单元格的前缀最大值的问题。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每 L 的强力模拟 | O(n m K) 或更糟 | O(n·m) | 太慢了|
 | 多源BFS+前缀处理| O(n m log(n m)) 或 O(n m + K) | O(n·m) | 已接受 |

 ## 算法演练

 1. 从网格上的所有 K 个人开始同时运行多源 BFS。 

每次移动花费 1 秒，因此计算任何人到达每个单元格的最短时间 dist[i][j]。 这是正确的，因为所有边都具有相同的权重，并且 BFS 按距离递增的顺序扩展。 
2. 将每个单元格存储为三元组（高度、距离、位置）。 

我们想要推理随着熔岩水平的增加网格如何变得不安全，这仅取决于高度排序。 
3. 按高度升序对所有单元格进行排序。 

这确保了当我们考虑阈值 L 时，所有变得不安全的单元在此排序中都是连续的。 
4. 构建一个数组 best[L]，表示所有高度 < L 的单元格之间的最大距离。 

我们扫描排序的单元格并维护运行的最大距离值。 
5. 对于从 1 到 n⋅m 的每个熔岩层 L，输出 best[L]。 

该值代表将被 L 级淹没的所有单元格中最坏情况的“逃生期限”。 
6. 如果 best[L] 未定义或对应于无法到达的配置（可以表示为无穷大），则输出 -1。 

### 为什么它有效

 BFS 计算任何人可以占据每个单元的最早时间。 如果某个单元被淹没在熔岩高度 L 处，则任何要求人员在其 BFS 到达时间之后进入该单元的配置都无法安全满足。 由于熔岩水平单调增加，不安全单元集随 L 单调增长。因此，对于每个 L，限制约束恰好是在该阈值下变得不安全的所有单元中的最大 BFS 到达时间。 这个最大值充分表征了等待更长时间是否允许可行的疏散计划。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, k = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    dist = [[10**18] * m for _ in range(n)]
    q = deque()

    for _ in range(k):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        if dist[x][y] == 10**18:
            dist[x][y] = 0
            q.append((x, y))

    dirs = [(1,0), (-1,0), (0,1), (0,-1)]

    while q:
        x, y = q.popleft()
        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m:
                if dist[nx][ny] > dist[x][y] + 1:
                    dist[nx][ny] = dist[x][y] + 1
                    q.append((nx, ny))

    cells = []
    for i in range(n):
        for j in range(m):
            cells.append((a[i][j], dist[i][j]))

    cells.sort()

    res = [0] * (n * m + 1)
    cur = 0
    best = 0

    idx = 0
    for L in range(1, n * m + 1):
        while idx < len(cells) and cells[idx][0] < L:
            best = max(best, cells[idx][1])
            idx += 1
        res[L] = best

    print(" ".join(str(res[i]) for i in range(1, n * m + 1)))

if __name__ == "__main__":
    solve()
```第一阶段使用标准 BFS 计算所有起始人员的最短距离。 这是至关重要的，因为运动是均匀的并且与熔岩高度无关。 

第二阶段将网格展平为按高度排序的列表，以便熔岩阈值对应于该列表的前缀。 

L 上的扫描保持了被淹没的细胞之间的运行最大距离。 这会将潜在的二次每次查询计算转换为排序后的单个线性扫描。 

初始化时必须小心：不可到达的单元格实际上处于无限远的距离，如果它们低于阈值，它们会迫使答案变大。 使用大哨兵可以确保正确性。

 ## 边缘情况

 当所有人都从同一个单元开始时，就会出现一个关键的边缘情况。 在这种情况下，BFS 会为该单元分配距离 0 并向外扩展。 远处的单元格可能有很大的距离，但只有当它们的高度包含在大 L 的前缀中时，它们才有意义。该算法仍然有效，因为对排序高度的扫描仅在需要时才会累积这些大距离。 

另一种边缘情况是存在多个不相连的低区域时。 BFS 正确地将大距离分配给其他组件中的单元格，因为移动受到网格邻接的限制。 当这些单元格成为前缀的一部分时，它们的大距离会正确地增加相应 L 值的答案。 

最后一种边缘情况是所有人都无法访问某些小区。 它们保持无限远的距离。 当这些单元格进入前缀时，它们会主导最大值，从而为较高的 L 值产生非常大的答案，这正确地反映了安全处理这些熔岩水平的可能性。
