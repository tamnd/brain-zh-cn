 ## 解决方案
 ## 问题理解

 我们得到了一张以字符串表示的多项选择题考试答卷。 每个位置对应一个问题，每个字符要么是A、B、C中的固定选择，要么是标有问号的未知数。 我们必须用三个选项之一替换每个问号。 

真正的正确答案有一个限制：没有两个连续的问题有相同的正确答案。 我们不知道正确的密钥，但我们知道它必须遵守这个规则。 对于我们填写的答案与未知的正确键匹配的每个位置，我们都会得分一分。 

不同之处在于，我们需要一种填充策略，能够在与约束一致的最坏可能有效正确密钥中最大化保证正确答案的数量。 换句话说，在我们承诺填写所有“？”之后，对手会选择与“没有相等的相邻字母”一致的有效答案键来最小化我们的分数。 我们希望选择能够最大化可达到的最低分数的填充物。 

输入由多个测试用例组成，每个测试用例都是长度最多为 100,000 的字符串。 测试的总大小足够大，任何对子串的二次或三次推理都会失败。 

一个天真的错误是认为局部贪婪地填充“？” 独立就足够了。 例如，在像“A？？？A”这样的模式中，选择局部一致的完成而不考虑全局约束可能会导致对手对齐有效的交替键，从而避免您猜测的所有结构。 

另一个微妙的失败来自于假设固定字母之间的每个段都可以独立优化而不考虑边界奇偶校验约束。 例如，在“A???B”中，端点之间的强制交替模式限制了哪些位置可以被强制正确。 

## 方法

 蛮力的想法是枚举所有填充每个“？”的方法。 与 A、B 或 C，并为每次完成计算与所有有效交替答案键匹配的最小数量。 仅填充的数量就“？”的数量而言是指数的，并且对于每个填充，有效键的集合也是指数的。 即使 N 约为 30，这也会很快变得棘手，因为 3^N 已经超出了可行的限制。 

关键的观察是我们并没有真正为每个位置独立选择答案。 “没有两个相邻的正确答案是相等的”约束意味着真正的答案键的行为就像在没有自循环的三个节点的完整图上行走。 对手的目标始终是选择一个有效的交替序列，尽可能避免匹配我们的固定选择。 

这将问题转化为相邻位置之间的局部一致性博弈。 重要的结构简化在于，只有连续位置之间的转换才重要，并且任何全局有效的键完全由其第一个字符决定。 之后，每个位置在剩余的两个字母之间交替，但确切的交替取决于之前的字符选择。 

因此，我们不必考虑任意键，而是可以考虑三个可能的起始字母以及每个起始选择可以在多大程度上与我们填充的字符串一致。 对于每个起始字母，对手的最佳响应是固定的，并且匹配的结果数量很容易计算。 

我们选择“？”的填充物 这样在最坏的情况下，最好的起始字母仍然能产生尽可能多的匹配。

 ## 算法演练

1. 对于每个测试用例，请考虑以下事实：任何有效答案键都是通过选择第一个字符，然后在每一步中交替选择其他两个选项来确定的。 这将有效键的空间减少到每个测试用例的三种可能性。 
2. 对于三个可能的起始字母 A、B 和 C 中的每一个，模拟随后的强制交替序列。 在位置 i 处，预期字符完全由 i 的起始字母和奇偶校验确定。 
3. 在模拟固定起始字母时，计算有多少个位置与输入字符串中的已知固定字符相匹配。 当输入有“？”时，我们将其视为灵活的，并假设可以对其进行最佳填充以保持这种对齐方式，因为我们在对手选择密钥之前控制了填充。 
4.对于每个位置i，如果s[i]是固定字符，我们不改变它。 如果它是“？”，我们从概念上将其设置为与当前模拟键匹配的最佳起始字母的字符，因为这最大化了该起始选择的保证匹配。 
5. 计算出每个起始字母的最佳可达到分数后，取三个值中的最大值。 这代表了我们在最坏情况键选择下的最佳填充策略。 

微妙的部分是填充和对手选择之间的相互作用。 由于对手的密钥受到限制，但与我们超出邻接有效性的填充选择无关，因此单独优化每个起始场景就足够了。 

### 为什么它有效

 任何有效的答案键都由其第一个字符唯一确定，并且邻接约束会强制随后进行确定性交替。 因此，对手的战略空间崩溃为三个结构化序列。 我们的填充可以解释为选择一个与这些序列中最好的序列最大程度一致的字符串。 由于一旦序列固定，每个位置都会独立贡献，因此问题分解为评估三个确定性比对并获取最佳结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def next_char(c):
    if c == 'A': return 'B', 'C'
    if c == 'B': return 'A', 'C'
    return 'A', 'B'

def simulate(start, s):
    n = len(s)
    cur = start
    best = 0

    for i in range(n):
        if s[i] == '?':
            best += 1
        else:
            if s[i] == cur:
                best += 1
        # move to next char in a valid alternating way
        if i + 1 < n:
            a, b = next_char(cur)
            cur = a
    return best

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    ans = 0
    for start in "ABC":
        ans = max(ans, simulate(start, s))

    print(ans)
```该代码评估三个可能的起始字母中的每一个，并模拟由该选择引起的独特交替序列。 功能`next_char`编码规则：任何字母都恰好有两个有效的下一个字母。 在模拟过程中，固定角色仅在与强制序列匹配时才做出贡献，而未知位置则自由贡献，因为我们始终可以分配它们以匹配所选场景。 

一个常见的实现陷阱是忘记我们不是验证任意序列，而是验证由固定开始引起的序列。 这就是为什么第一个字符之后的转换是确定性的。

 ## 边缘情况

 一个关键的边缘情况是字符串完全由“?”组成。 在这种情况下，任何交替模式都是可以实现的，并且最佳策略是与三个确定性序列之一完全对齐。 该算法通过为任何选定的开始的每个位置给予充分的积分来处理这个问题，因为每个位置都被视为可匹配的。 

另一个微妙的情况是固定字符出现稀疏但严重限制最佳开始。 例如，在“A???C”中，只有两个端点都一致才能获得高分。 模拟正确地评估了所有三个起始点，并且只有兼容的起始点才能产生最大对齐，从而避免了不正确的贪婪局部填充。 

最后的边缘情况是长度为 1 或 2 的短字符串，其中交替约束是微不足道的。 该算法仍然统一对待它们，并且每次启动都会产生正确的评估，因为不存在转换歧义。
