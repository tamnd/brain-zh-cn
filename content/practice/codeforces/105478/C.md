 ## 解决方案
 ## 问题理解

 每个测试用例都给出了一个商店，其结构为几个独立的物品堆栈。 在每个堆栈中，项目从上到下按固定顺序排列，只有当您已经购买了堆栈中的下一个项目时，您才可以访问该堆栈中的下一个项目。 因此，对于任何堆栈，您的选择都不是任意子集，而是该堆栈的前缀。 

每件物品都有一个价值，购买它会增加你的总攻击力。 所有物品都花费相同数量的硬币，因此限制纯粹在于你能买得起多少物品，而不是具体是哪些物品。 

这将问题转化为选择所有堆栈中的项目总数，但在每个堆栈中，如果您要获取任何内容，则必须采用前缀。 目标是以最大化所选价值总和的方式将有限数量的购买分配到各个堆栈中。 

一个微妙的点是允许负值。 这使得有时即使您有能力，也最好从堆栈中取出较少的项目，因为更深的项目会降低您的总分。 这排除了任何假设“物品越多越好”的贪婪策略。 

从限制来看，堆栈的数量最多为250个，并且每个堆栈可以相当长。 金币上限提升至3000个，但每件物品需要15个金币，这意味着你实际可以购买的物品数量最多为200个。这种减少是关键的结构简化：虽然输入看起来很大，但有效的背包容量却很小。 

一个天真的解释会尝试模拟跨堆栈的前缀长度的所有有效组合。 如果堆栈 i 有 mi 选项，则总组合随着 (mi + 1) 的乘积而增长，即使对于中等输入，它也会变得天文数字般大。 即使尝试 N 个堆栈中 C 个项目的所有分布也会导致组合爆炸。 

打破粗心解决方案的边缘情况包括所有负值的堆栈，其中最佳选择是从该堆栈中取出零个项目，以及早期项目为负但后来的项目为正的堆栈，迫使仔细的前缀推理。 例如，像这样的堆栈`[-5, -2, 10]`有前缀和`[-5, -7, 3]`，最好的选择是接受所有三个项目，即使中间的前缀非常糟糕。 任何贪婪的“当它变成负数时就停止”的方法在这里都失败了。 

另一个边缘情况是 C 不能被 15 整除。由于每个商品的成本相同，真正的约束是商品的数量，因此我们可以有效地使用`C // 15`。 

## 方法

 暴力视图是为每个堆栈分配一定数量的商品 k_i，计算每个堆栈的前缀值，并强制所有 k_i 的总和等于我们可以购买的商品数量。 对于每个堆栈 i，我们可以尝试从 0 到 m_i 的所有 k_i，并检查跨堆栈的所有组合。 

这在概念上是可行的，因为它直接遵循问题的规则，但在计算上却失败了，因为分支因子在堆栈之间相乘。 即使每个堆栈只有 50 个选择，250 个堆栈也会使状态空间完全不可行。 

关键的观察结果是，除了总项目的共享预算之外，每个堆栈的决策都是独立的。 一旦我们预先计算出从堆栈中取出 k 个项目的值（这只是一个前缀和），每个堆栈就成为多项选择背包问题中的一个组。 然后我们只需要在组之间分配总共 K 个项目，其中 K 最多为 200。 

这将问题从指数组合选择简化为堆栈和项目计数的结构化动态编程。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有前缀组合进行暴力破解 | 指数| 指数| 太慢了 |
 | 堆栈和项目预算的动态规划| O(N·K·平均 m_i) | O(K) | 已接受 |

 ## 算法演练

 设 K 为我们能买得起的物品数量，计算公式为`K = C // 15`。 

1. 对于每个堆栈，计算前缀和，以便我们可以在 O(1) 时间内回答如果我们获取前 k 个项目会发生什么。 这会将每个堆栈转换为一个列表，其中索引 k 表示恰好获取 k 个项目的值。 
2.维护一个DP数组，其中`dp[x]`表示在处理一些堆栈并总共获取 x 个项目后可实现的最大攻击。 最初，`dp[0] = 0`所有其他状态都是负无穷大。 
3. 进程堆栈一一进行。 对于每个堆栈，构建一个新的 DP 数组`ndp`。 对于每个可能的先前总 x 和此堆栈中每个可能的选择 k，我们过渡到`x + k`items并添加相应的前缀值。 此步骤反映了我们在考虑总容量的同时独立决定从当前堆栈中取出多少项的想法。 
4. 处理完所有堆栈后，答案是所有 dp[x] 的最大值，其中 x ≤ K，因为我们可以保留未使用的容量。 

转换中的关键点是我们永远不会混合来自同一堆栈的部分决策，因为前缀约束强制每个堆栈有一个连续的选择。 

### 为什么它有效

 在处理 i 个堆栈后的任何时刻，每个 dp 状态都对应于从这些 i 个堆栈中对前缀的某些有效选择。 不变的是 dp[x] 存储通过从处理的堆栈中精确选择 x 项来实现的最佳攻击值，并遵守前缀约束。 当我们处理一个新的堆栈时，我们通过为该堆栈选择一个前缀长度来扩展每个现有的配置。 由于所有有效的解决方案都必须为每个堆栈做出一个这样的选择，因此不会错过任何有效配置，也不会引入无效配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

NEG = -10**30

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        N, C = map(int, input().split())
        K = C // 15
        
        stacks = []
        for _ in range(N):
            arr = list(map(int, input().split()))
            m = arr[0]
            vals = arr[1:]
            
            pref = [0]
            s = 0
            for v in vals:
                s += v
                pref.append(s)
            
            # truncate to K since we never need more than K items
            pref = pref[:min(len(pref), K + 1)]
            stacks.append(pref)
        
        dp = [NEG] * (K + 1)
        dp[0] = 0
        
        for pref in stacks:
            m = len(pref) - 1
            ndp = [NEG] * (K + 1)
            
            for used in range(K + 1):
                if dp[used] == NEG:
                    continue
                base = dp[used]
                for take in range(m + 1):
                    if used + take <= K:
                        val = base + pref[take]
                        if val > ndp[used + take]:
                            ndp[used + take] = val
            
            dp = ndp
        
        out.append(str(max(dp)))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```实现直接遵循DP结构。 每个堆栈的前缀数组都是增量构建的，因此每个“获取 k 项”决策的时间复杂度为 O(1)。 DP 数组的大小由 K 而不是 C 决定，这一点很重要，因为 C 本身是硬币，但真正的约束是项目数量。 

双循环结束`used`和`take`是安全的，因为转换后 K 最多为 200，使得在最坏情况下每个堆栈的转换约为 40,000 次操作，这很合适。

 ### 示例 1

 输入：```

| 堆栈| 前缀和 |

 | 2 | [0, -1, -2, 1] |

 DP进化：

 | 步骤| dp[0] | dp[0] | dp[1] | dp[1] | dp[2] | dp[2] |
 | --- | --- | --- | --- |
 | 开始 | 0 | -inf| -inf|

 堆栈 1 之后：

 | 二手 | 采取| 新状态|
 | --- | --- | --- |
 | 0 | 0 | 0 |
 | 0 | 1 | -2 |
 | 0 | 2 | -1 |

 dp 变为：`[0, -2, -1]`在堆栈 2 之后，最佳组合是单独从堆栈 2 中取出前缀 3（值 1）或仔细组合，但容量限制会导致最佳结果 0。 

这表明负中间值仍然可能导致跳过或限制选择。

 | 测量 | 复杂性 | 说明|

 | 时间 | 最坏情况 | O(N·K²) 对于每个堆栈，我们尝试所有先前使用的计数和所有前缀长度 |
 | 空间| O(K) | 仅存储两个DP数组|

 ## 边缘情况

 仅包含负值的堆栈是自然处理的，因为前缀数组始终包含空选择。 DP 将传播采用零项的选项，保留非负基线。 

像这样的案例`[-5, -2, 10]`演示了为什么前缀结构很重要。 DP 考虑所有 k 值，尽管中间前缀更差，但采用 k = 3 变得最优，因为它是显式评估而不是贪婪地推断。 

当C小于15时，K变为零，并且DP立即返回零，因为无法购买任何物品。
