 ## 解决方案
 ## 问题理解

 安德鲁在一天中的某个特定时间醒来，发现他的猫饿了。 猫一开始有一些初始饥饿值，并且随着时间的推移，这种饥饿值以每分钟固定的速度稳定增长。 安德鲁只能通过买面包来减少猫的饥饿感。 每个包子会减少固定数量的饥饿感，并且可以随时购买任意数量的包子，无需旅行成本或时间延误。 

定价方面有一个重要的转变。 20:00之前，每个包子按正常价格出售。 从 20:00 开始，每个面包都会便宜 20%。 折扣适用于购买每个小圆面包，而不是每个小圆面包，并且允许部分付款，因为折扣价格可以是非整数，但小圆面包仍然是不可分割的。 

目标是决定安德鲁应该什么时候去商店以及他应该购买多少个面包，以便猫最终的饥饿感变得消极，同时最大限度地减少总花费。 

问题的关键张力在于两个线性过程之间。 随着时间的推移，等待会线性增加饥饿感，而如果超过 20:00 阈值，等待可能会降低每个面包的价格。 这会创建少量有意义的决策点，而不是连续的优化问题。 

从限制条件来看，饥饿值最高可达 100000，每分钟最多增长 100。 时间受单日时钟限制。 没有必要在每一分钟内进行简单的模拟。 任何以嵌套方式每分钟或每个面包重新计算的解决方案都会面临最坏情况约 10^7 到 10^10 次操作的风险，并且速度太慢。 该结构表明，只有恒定数量的候选购买次数才重要。 

一个微妙的情况是 Andrew 在 20:00 之前醒来并考虑等待。 由于饥饿感增加，等待会增加所需的面包，但会降低每个面包的价格。 另一种情况是 Andrew 在 20:00 后醒来，此时只有折扣制度才重要。 第三种边缘情况是当等待时间正好是 20:00 时，因为折扣会在一个尖锐的边界处激活。 

## 方法

 暴力方法会尝试从起床到一天结束的所有可能的分钟，计算由此产生的饥饿感，计算当时需要多少个面包，然后乘以相应的价格。 对于每个候选分钟，我们将计算一个上限划分来确定面包数量。 

这是可行的，因为每分钟的状态都定义良好，但速度太慢，因为一天最多有 1440 分钟，并且每次评估都是 O(1)，每次测试大约需要 10^3 次迭代。 仅此一点就很好，但如果扩展或嵌入多个计算中或错误地推广到更大的时域，它就会变得低效。 更重要的是，真正的冗余是概念上的而不是数字上的。 

关键的观察是只有两个时刻重要。 安德鲁要么立即购买，要么等到折扣生效的第一刻。 20:00 之后的任何时间都比在 20:00 正好购买更糟糕，因为饥饿只会增加，而价格保持不变。 同样，从起床到 20:00 之间的任何时间都相当于“立即购买”，因为折扣前价格不会改变。 

这将问题简化为评估最多两种情况，在每种情况下使用上限除法计算所需的面包，并选择更便宜的结果。

 ## 算法演练

 我们通过比较一小组候选策略来计算答案。 

### 1. 将折扣前的时间转换为分钟

 我们计算从起床时间到 20:00 还剩多少分钟。 如果 Andrew 在 20:00 或之后醒来，则该值为零。 

这决定了是否存在“等待折扣”策略。

### 2.定义立即购买状态

 如果安德鲁立即购买，饥饿度正是初始值 H。需要的面包数量是满足 k·N ≥ H 的最小整数 k。 

这是标准的天花板划分。 

### 3. 计算立即购买的成本

 折扣前每个面包的价格为 C。 总成本为 k·C。 

### 4.定义折扣时购买状态

 如果 Andrew 等到 20:00，则在计算的等待时间 t 内，饥饿感每分钟 D 线性增加。 

所以饥饿就变成了H+t·D。 

### 5.计算折扣下的包子

 20:00 或之后，每个包子的价格为 0.8·C。包子的数量再次达到上限((H + t·D) / N)。 

### 6. 如果已经在 20:00 之后

 在定价选择方面，我们完全跳过直接案例，因为折扣已经适用。 我们只计算当前的折扣版本。 

### 7. 选择最低成本

 我们比较有效的策略并输出最小的成本。 

### 为什么它有效

 关键的不变量是，对于 20:00 之前的任何时间间隔，每个面包的价格保持不变，而饥饿感严格增加。 这使得所需的小圆面包数量成为等待时间的非递减函数，而每个小圆面包的成本保持不变。 20:00之后，在保持价格固定的情况下，等待更长的时间只会增加饥饿感，因此成本函数严格不随时间递减。 因此，任何最优解都必须出现在价格机制变化的边界点或初始时刻。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ceil_div(a, b):
    return (a + b - 1) // b

hh, mm = map(int, input().split())
H, D, C, N = map(int, input().split())

start = hh * 60 + mm
discount_time = 20 * 60

# time until discount becomes active
t = max(0, discount_time - start)

# option 1: buy immediately
buns_now = ceil_div(H, N)
cost_now = buns_now * C

# option 2: buy at or after 20:00 (only meaningful if t > 0 or already past)
H_later = H + t * D
buns_later = ceil_div(H_later, N)
cost_later = buns_later * C * 4 / 5

# if already after 20:00, only one regime matters
if start >= discount_time:
    print(f"{cost_later:.10f}")
else:
    print(f"{min(cost_now, cost_later):.10f}")
```该实现首先将时间转换为分钟，以简化与固定阈值 20:00 的比较。 辅助函数实现了上限除法，这是确定满足给定饥饿水平所需的最小面包数量所必需的。 

这两个候选成本直接对应于两个有意义的策略：立即以全价购买，或者等到折扣时间并在饥饿增加后以降价购买。 最后通过比较选择更好的选项。 

一个常见的错误是忘记不应进一步模拟超过 20:00 的等待，因为成本函数只会在折扣开始后恶化。

 ### 示例 1

 输入：```

```我们计算 20:00 之前还有 60 分钟。

 等待是有益的，因为折扣超过了额外的饥饿增加。

 输入：```

```我们计算距离折扣还有 90 分钟。 

| 步骤| 饥饿| 包子数| 每个面包的价格| 总成本|
 | --- | --- | --- | --- | --- |

这两个案例显示了核心权衡：只有当每个面包节省的折扣超过所需的额外面包时，等待才有帮助。

 ## 边缘情况

 一个关键的边缘情况是 Andrew 在 20:00 准时醒来。 在这种情况下，等待不会改变任何事情，因为折扣已经生效。 该算法通过将等待时间设置为零来处理此问题，这将两种策略折叠为折扣策略。 

当饥饿感小于面包大小时，会出现另一种边缘情况。 在这种情况下，上限除法会正确返回一个圆面包，从而防止任何下溢逻辑或零圆面包错误。 

第三种情况是，等待会显着增加饥饿感，但折扣只会略微降低价格。 两个计算成本之间的比较正确地捕捉到了这种不平衡，而不需要任何启发式推理。
