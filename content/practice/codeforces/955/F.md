 ## 解决方案
 ## 问题理解

 我们有一棵有根的树$n$节点，以节点 1 为根。对于每个节点$u$，我们考虑由整数定义的一系列结构$k$，其中一个节点可以被认为是“$k$- 深度堆$m$“如果它至少有$k$子子树本身至少表现得像深度堆$m-1$。 叶子简单地形成深度为 1 的堆。 

对于每个节点$u$和每个$k$，我们定义$\mathrm{dp}_k(u)$作为此类的最大可能深度$k$-ary 堆植根于以下子树内的某个位置$u$， 和$u$允许作为该堆的根。 最终任务是计算每个节点和每个节点上所有这些值的总和$k$，隐含的界限是$k$范围涵盖所有可以做出有意义贡献的价值观。 

该结构不是关于固定堆，而是关于每个节点可以支持多少个不相交的“足够深”的子分支。 参数$k$就像一个阈值：增加$k$使节点更难维持大深度。 

约束条件$n \le 3 \cdot 10^5$排除任何尝试重新计算的解决方案$\mathrm{dp}_k(u)$对于许多人来说是独立的$k$每个节点的值。 甚至一个$O(n^2)$对的解决方案$(u,k)$太大了。 任何可接受的方法都必须跨节点和跨值重用信息$k$，理想情况下利用贡献的单调性或全局排序。 

一个天真的解释会尝试模拟，对于每个节点$u$，增加值$k$并反复检查可以形成多深的堆。 这很快就变得不可行，因为每次检查都需要递归扫描子项，导致至少$O(n^2)$或者更糟。 

当一个节点有许多子树深度相似的子节点时，就会出现微妙的失败情况。 例如，如果一个节点有 10 个子节点，全部形成深度 5 的链，那么对于小$k$深度为 5，但作为$k$增加到超过 10 时，它会崩溃为 1。任何不仔细跟踪子深度多重性的简单重新计算都会高估或错误计算贡献。 

另一个边缘情况是星形树，其中节点 1 连接到所有其他节点。 在这种情况下，所有非根节点的 dp 值严重依赖于$k=1$，而根的轮廓急剧减小为$k$增加。 许多不正确的方法假设单调平滑衰减，而不考虑当$k$第三大的孩子消失了。 

## 方法

 关键的难点在于$\mathrm{dp}_k(u)$取决于有多少个孩子$u$至少达到深度$m-1$，这个阈值结构表明对于固定$u$，跨越的行为$k$完全由排序的子贡献决定。 

暴力策略将计算$\mathrm{dp}_k(u)$每个独立地$k$。 对于固定对$(u,k)$，人们可以尝试通过迭代检查有多少孩子满足增加所需的条件来计算深度$m$。 每次检查都需要聚合子树结果，成本计算$O(\deg(u))$每一步和潜在的$O(n)$步骤，给予$O(n^2)$在最坏的情况下，就像星树一样，每个节点。 这已经远远超出了极限。 

关键的见解是扭转观点。 而不是修复$k$，我们固定深度$m$。 对于一个节点$u$，问：至少有多少个孩子有子树深度$m-1$？ 设这个数为$c_u(m)$。 然后$u$支持深度$m$为所有人$k \le c_u(m)$。 这将问题转换为计算，对于每个节点和每个可能的深度级别，有多少个值$k$是有效的。 

这将计算转移到为每个节点维护可以以贪婪方式组合的子贡献的多集。 该结构变得类似于计算“我可以重复采取多少次$k$-来自儿童的阶次统计”。

 然后，我们为每个节点计算其子节点可实现深度的频率表，将它们聚合成排序结构，并得出每个深度间隔对最终总和的贡献。 因为每个节点的深度值最多是$O(\log n)$平均而言，在合并约束下，我们可以使用 DFS 和从小到大的合并或基于优先级的聚合来有效地维护这些。 

最后，不是计算所有$\mathrm{dp}_k(u)$明确地，我们通过观察每个节点的贡献来累积贡献$m$致所有人$k \le c_u(m)$。 每个这样的间隔都会贡献一个三角计数$k$，可以总结为$O(1)$每个间隔。

 | 蛮力 |$O(n^2)$或者更糟|$O(n)$| 太慢了|
 | 最佳|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将问题重新表述为计算，对于每个节点，有多少个子节点支持每个可能的深度级别，然后将其转化为贡献$k$。 

### 步骤

 1. 将树的根设为 1，并按 DFS 顺序计算树。 

这确保了每个子树都在其父树之前得到处理，因此子树信息在需要时始终可用。 
2.对于每个节点$u$, 定义一个多重集$S_u$包含表示每个子项贡献的最大堆深度的值。 

这种抽象使我们能够忽略结构，只关注子树的“强度”。 
3. 按后序处理节点。 对于一片叶子，设置$S_u = \{1\}$。 

叶子只能形成深度为 1 的堆，无论$k$。 
4. 对于内部节点$u$，合并所有子多重集$S_v$成一个结构。 

合并步骤聚合所有可能的子树深度$u$可以依靠。 
5. 转换$S_u$放入已排序的数组中$a_u$。 

排序至关重要，因为堆条件仅取决于“至少$k$孩子们”。
 6. 对于每个深度阈值$m$，计算中有多少个元素$a_u$至少是$m-1$。 

这个计数直接给出了最大可行$k$对于哪个深度$m$是可以实现的。 
7. 积累节点贡献$u$通过总结所有$m$：每个深度$m$贡献$m$致所有人$k \le c_u(m)$。 

这将二维相关性转换为间隔计数。 
8. 向上合并结果，以便父节点重用已经聚合的信息。 

这可确保每次合并操作仅处理每条边一次。 

### 为什么它有效

 在每个节点$u$，可能的堆深度的结构完全取决于有多少子子树可以支持给定的深度阈值。 关键的不变量是处理后$u$, 多重集$S_u$正确编码所有可能的子树深度$u$。 由于堆条件仅取决于超过阈值的子项计数，因此排序会保留所有必要的信息，并且不会丢失任何结构细节。 

每个贡献都被计算一次，因为每一对$(u, m)$映射到有效的唯一间隔$k$，并且这些区间在聚合时是不相交的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

ans = 0

def dfs(u, p):
    global ans
    depths = []

    for v in g[u]:
        if v == p:
            continue
        child_depths = dfs(v, u)
        depths.extend(child_depths)

    if not depths:
        ans += 1
        return [1]

    depths.sort(reverse=True)

    cnt = 0
    freq = {}

    # compute contribution of u
    for i, d in enumerate(depths, 1):
        if d >= i:
            cnt = i
        else:
            break

    ans += cnt + 1

    new_depth = cnt + 1
    return depths[:cnt] + [new_depth]

dfs(0, -1)
print(ans)
```DFS 为每个节点计算其子节点可达到的深度列表。 该列表已排序，因此我们可以贪婪地将最大深度与最小所需位置进行匹配，这模拟检查有多少子级可以支持增加的堆深度。 

变量`cnt`表示可以维持一系列不断增加的深度约束的子级的最大数量。 一旦计算出来，节点就会通过以下方式贡献所有以其为根的有效堆配置：`cnt + 1`。 

返回值将子树压缩为简化的表示，仅保留最强的贡献者加上节点本身新形成的深度。 这可以防止存储状态呈指数增长。 

由于树可以是长链，因此增加了递归限制，否则 Python 的默认限制将溢出。

 ## 边缘情况

 类似路径的树是递归最干净的压力情况。 每个节点只有一个子节点，因此排序深度列表的大小始终为一。 该算法分配`cnt = 1`在每个内部节点处，产生一致的向上深度传播，而不会出现任何组合爆炸。 

星形树最明显地暴露了阈值行为。 在根部，子深度列表很大但都等于 1，因此只有$k=1$有助于增加深度。 算法正确计算`cnt = 1`，防止如果错误地假设更多的孩子自动意味着更高的深度，就会发生高估。 

完美平衡的二叉树测试合并是否保持对称性。 在每个级别，子深度列表均匀地组合，并且贪婪匹配确保只有足够深的子树对才对更高级别做出贡献，从而保持聚合贡献的正确性。
