 ## 解决方案

 ## 问题理解

 该任务是关于计算可以表示为完美幂的数字。 对于每个查询，我们都会得到一段整数$[L, R]$，我们需要计算该段内有多少个整数可以写成以下形式$x = a^p$， 在哪里$a$是一个正整数和指数$p$严格大于1。 

换句话说，我们正在计算一个范围内的所有数字，这些数字是完美的平方、完美的立方、完美的四次方等等。 即使同一数字有多种表示形式，也只能计算一次，例如 64 既是$2^6$,$4^3$， 和$8^2$。 

输入大小清楚地表明我们不能通过扫描间隔来处理每个查询。 范围端点达到$10^{18}$，这会立即排除任何每个数字的迭代。 即使是单个查询也会太大而无法枚举。 

一个更微妙的限制是查询的数量，最多$10^5$。 这促使我们采用预计算策略：我们需要一次构建所有相关数字的全局结构，然后通过快速范围计数来回答查询。 

边缘情况源于权力之间的重叠。 一种简单的方法可能会通过指数独立地计算幂，例如分别计算所有平方、所有立方、所有四次方并求和。 这会多次超出 64 或 729 之类的数字。 另一个陷阱是浮点根计算，它可能会在边界附近引入精度误差，例如$10^{18}$，其中舍入可能会错误地包含或排除诸如$999999999999999999$。 

## 方法

 蛮力的想法是通过迭代中的所有整数来处理每个查询$[L, R]$并检查每个数字是否是完美幂。 检查一个数字涉及尝试所有指数$p \ge 2$，计算整数根并通过求幂进行验证。 这在概念上是可行的，但范围可以大到$10^{18}$，因此即使是单个查询也会退化为不可行的工作。 

关键的观察是，所有完美幂的集合$10^{18}$其实很小。 对于固定指数$p$，最大的基地$a$满意的$a^p \le 10^{18}$迅速减少为$p$成长。 为了$p = 2$，我们有关于$10^9$候选人，但对于$p = 3$仅关于$10^6$，之后又迅速下降。 一次$p > 60$， 甚至$2^p$超过了限制，所以不同完美幂的总数最多只有几百万个量级，而去重后就少得多。 

这提出了一种预处理策略：生成所有完美的幂$10^{18}$，将它们存储在排序列表中，删除重复项，然后使用二分搜索回答每个查询以计算有多少个属于$[L, R]$。 

从蛮力解决方案到最优​​解决方案的转变来自于认识到昂贵的工作独立于查询。 一旦所有有效值都被预先计算，每个查询就会减少到两次二分搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(Q \cdot (R-L))$|$O(1)$| 太慢了|
 | 最佳|$O(N \log N + Q \log N)$|$O(N)$| 已接受 |

 这里$N$是不同完美幂的数量，最多可达$10^{18}$。 

## 算法演练

 1.生成所有完美的力量$10^{18}$通过迭代指数$p$从2开始向上。 对于每个指数，计算所有有效底数$a$这样$a^p \le 10^{18}$。 上限为$a$是整数$\lfloor (10^{18})^{1/p} \rfloor$。 
2. 对于每个基地$a$, 计算$a^p$使用整数乘法或快速求幂。 如果结果超过$10^{18}$, 停止增加$a$对于该指数，因为值只会增长。 
3. 将每个计算值插入到一个集合中以避免重复，因为像 64 或 729 这样的数字可以由多个指数碱基对生成。 
4. 生成完成后，将集合转换为排序数组。 
5. 对于每个查询$[L, R]$，使用二分查找计算有效完美幂的数量：计算有多少个元素$\le R$减去多少个$< L$。 

二分查找在这里有效的原因是预先计算的列表是严格排序的，因此前缀计数变得高效且可靠。 

### 为什么它有效

 每个数字都可以写成$a^p$为了$p > 1$重复数据删除后，在生成集中仅出现一次。 生成过程涵盖了范围内的所有有效指数和所有有效基数，因此不会遗漏任何有效数字。 排序保留顺序，二分查找正确隔离段$[L, R]$，确保每个查询都作为静态有序集上的纯计数问题来回答。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

LIMIT = 10**18

def generate():
    vals = set()

    p = 2
    while True:
        # smallest base is 2^p; if already too large, stop
        if 2 ** p > LIMIT:
            break

        a = 2
        while True:
            v = pow(a, p)
            if v > LIMIT:
                break
            vals.add(v)
            a += 1

        p += 1

    vals.add(1)  # 1 = 1^p for any p > 1
    return sorted(vals)

vals = generate()

def count_le(x):
    lo, hi = 0, len(vals)
    while lo < hi:
        mid = (lo + hi) // 2
        if vals[mid] <= x:
            lo = mid + 1
        else:
            hi = mid
    return lo

q = int(input())
out = []

for _ in range(q):
    L, R = map(int, input().split())
    out.append(str(count_le(R) - count_le(L - 1)))

print("\n".join(out))
```该代码首先构建了完美权力的完整宇宙，最高可达$10^{18}$。 指数和底数上的嵌套循环由限制检查控制，即使理论搜索空间很大，也能确保终止。 

包含 1 是显式的，因为它是一种特殊情况：它是有效的$a^p$对于任何$p > 1$，但否则会被从 2 开始的基本迭代错过。 

的`count_le`函数执行标准的二分搜索来计算前缀元素的数量。 这避免了依赖库函数并使边界处理明确，特别是之间的区别$\le R$和$< L$。

 ## 边缘情况

 一个重要的边缘情况是包含 1。因为 1 等于$1^p$对于每个有效指数，必须显式添加或单独处理。 如果不这样做，查询就像$[1, 1]$会错误地返回零。 

另一个微妙的情况是重叠表示，例如 64。在生成过程中，它可以显示为$2^6$,$4^3$， 和$8^2$。 如果我们不使用集合来消除重复，则二分搜索结果将过度计数，因为重复会人为地增加频率。 

最后，上限$10^{18}$接近浮点精度极限。 任何方法使用`math.pow`或者浮点根提取有错误分类边界值的风险，例如$10^{18}$或者$999999999999999999$。 基于整数的生成通过仅使用精确的整数乘法并在溢出时停止来完全避免这种情况。
