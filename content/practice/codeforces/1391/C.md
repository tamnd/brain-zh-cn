 ## 解决方案
 ## 问题理解

 我们得到了数字的排列`1...n`。 根据该排列，在数组的索引上构建了一个图。 

对于每个职位`i`，只要存在这样的元素，我们就将其连接到左侧最近的较大元素和右侧最近的较大元素。 该图是无向的。 

如果生成的图至少包含一个简单循环，则一种排列称为循环排列。 任务不是为特定排列构建图表。 相反，我们只得到`n`，我们必须计算有多少种长度排列`n`生成包含循环的图。 

答案必须以模数形式报告`10^9 + 7`。 

约束是关键观察。 这里`n`可以大到`10^6`。 这么大的值会立即排除任何对个体排列进行推理的方法。 有`n!`排列，甚至生成它们也是不可能的。 我们需要一个纯数学计数公式，其值可以在线性或近线性时间内计算。 

图的构造看起来很复杂，但约束强烈表明最终答案必须取决于所有此类图的结构属性，而不是逐一检查排列。 

一个常见的错误是假设图表可以包含许多不同类型的循环，并且我们必须直接对它们进行计数。 例如，对于`n = 4`， 有`24`排列和手动检查周期似乎是可行的。 为了`n = 10^6`，这种观点是没有希望的。 

另一个简单的陷阱是计算图连通的排列。 连通性与包含循环不同。 树是连通的且无环的。 事实证明，这种区别正是解决方案的关键所在。 

## 方法

 强力解决方案将生成每个排列、构建图并运行 DFS 等图算法来检测循环。 

对于单个排列，可以使用单调堆栈来找到每一侧最近的较大元素`O(n)`。 循环检测也是`O(n)`。 因此，可以在线性时间内处理一种排列。 

问题是排列的数量。 有`n!`其中。 即使是为了`n = 15`，这已经是关于`1.3 × 10^12`的可能性。 暴力方法几乎立即变得无法使用。 

突破来自于对这种构造生成的图的理解。 

该图是著名的笛卡尔树图。 如果我们取排列的最大元素，它就成为根。 递归地，其左侧的元素形成左子树，右侧的元素形成右子树。 

关键的属性是语句中构造的图始终是连通的。 除了最大元素之外的每个节点都至少有一个到更大元素的连接，因此每个顶点最终都可以达到全局最大值。 

现在考虑边的数量。 

每个位置最多可以向左侧最近的较大元素贡献一条边，向右侧最近的较大元素贡献一条边。 对该结构的更深入分析表明，所得到的图恰好具有`n - 1`当且仅当排列对应于没有分支循环的笛卡尔树时才具有边。 事实上，当最大元素位于排列的一端时，该图正是一棵树，并且递归地，相同的属性适用于其余两个部分。 

该递归条件表征可通过将当前最大剩余值重复放置在左端或右端而获得的排列。 

存在多少种这样的排列？ 

地方`n`第一的。 它必须在一端。 

移除后`n`，同样的条件必须成立`n-1`。 

对于每个值`n`下降到`2`，我们独立选择它是转到剩余序列的左端还是右端。 

这正好给出了`2^(n-1)`图是树的排列。 

由于每个排列都会产生一个连通图，因此当图不是树时，它就是循环图。 

排列总数为`n!`。 

因此：$$\text{cyclic permutations} = n! - 2^{\,n-1}$$所有计算均以模进行`10^9+7`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n·n!) | O(n·n!) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`n`。 
2. 计算`n! mod M`， 在哪里`M = 10^9 + 7`。 
3. 计算`2^(n-1) mod M`。 
4. 从第一个模数中减去第二个值`M`。 
5. 输出结果。 

唯一重要的部分是计数参数。 一旦我们知道非循环图正是递归的最终最大排列，对它们的计数就变成了简单的 2 的幂。 

### 为什么它有效

 构造生成的每个图都是相连的。 上的连通图`n`顶点是非循环的当且仅当它恰好包含`n-1`边，这意味着它是一棵树。 

The permutations that produce trees are exactly those where the current maximum element always appears at one of the ends of the current interval. 删除最大值不会分割任何内容，并且相同的条件必须递归地保留剩余元素。 

建立这样一个从最大到最小的排列，每个值都有两个选择，左端或右端。 有`n-1`独立决策，产出`2^(n-1)`生成树的排列。 

由于有`n!`总排列，产生至少一个循环的数是$$n! - 2^{n-1}.$$## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n = int(input())

fact = 1
for i in range(2, n + 1):
    fact = (fact * i) % MOD

trees = pow(2, n - 1, MOD)

print((fact - trees) % MOD)
```直接按照计数公式实现。 

第一个循环计算`n!`模数`10^9+7`。 自从`n ≤ 10^6`，一百万次模乘法很容易足够快。 

Python 的内置模幂计算`2^(n-1)`在`O(log n)`时间。 

减法以模进行`MOD`。 表达式```
(fact - trees) % MOD
```正确处理负中间值。 

不使用递归，这避免了最大输入的递归深度问题。 

## 工作示例

 ### 示例 1

 输入：```
4
```计算这两个量。 

| 步骤| 价值|
 | ---| ---|
 |`4!`| 24 |
 |`2^(4-1)`| 8 |
 | 回答 | 24 - 8 = 16 | 24 - 8 = 16

 输出：```

```这与样本相符。 

该迹线演示了中心计数原理：所有 24 个排列都分为 8 个生成树排列和 16 个循环排列。

其余两个排列产生循环。

 ## 边缘情况

 考虑最小的有效输入：```
3
```该算法计算$$3! - 2^2 = 6 - 4 = 2.$$计数论点仍然适用。 恰好有四种生成树的排列和两种循环排列。 无需特殊处理。 

考虑减法将变为负模的情况`MOD`。 对于较大的值`n`， 两个都`n! mod MOD`和`2^{n-1} mod MOD`是残数，不是原始数字。 完全有可能$$(n! \bmod MOD) < (2^{n-1} \bmod MOD).$$使用```
(fact - trees) % MOD
```自动将结果转换为正确的残差类，避免常见的模算术错误。 

考虑最大输入：```
1000000
```该算法执行一百万次模乘法和一次模幂运算。 没有正比于的数组`n`已分配，并且不使用递归。 该解决方案在内存和时间限制内保持舒适。
