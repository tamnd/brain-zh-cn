 ## 解决方案
 ## 问题理解

 我们得到一叠从上到下排列的大写字母。 任务是通过重复删除当前顶部卡或当前底部卡，并将所选卡附加到新序列的末尾，将这些卡重建为新序列。 目标是产生字典顺序尽可能最小的最终字符串。 

关键的限制是，在每一步我们只有两个选择，并且一旦选择了一个字符，它就会永久地放置在结果的末尾。 这意味着早期决策可能会阻碍更好的全球结果，因此必须仔细证明贪婪选择的合理性。 

输入大小可达500,000张卡片。 这立即排除了任何模拟所有可能选择或回溯的解决方案。 即使 O(n^2) 方法也太慢了。 我们需要能够对每个字符进行恒定次数的处理，或者最坏的情况是对数处理。 

当顶部和底部之间的局部比较不充分时，就会出现微妙的失败情况。 例如，如果顶部是“B”，底部是“A”，则采用“A”似乎是正确的。 然而，真正的决定取决于这些信件背后的内容。 如果选择一侧后剩余的后缀在字典顺序上更差，则天真的贪婪选择就会失败。 

一个小插图：

 输入：

 A B C D E

 如果我们总是选择两端中较小的一端，那么在以下情况下我们可能会选择错误：

 A ... Z 与 A ... Y

 正确的决定取决于更深入的后缀比较，而不仅仅是当前端点。 

## 方法

 蛮力策略尝试从左端或右端选择所有可能的序列。 每个状态分支为两种可能性，形成高度为 n 的二元决策树。 这会导致 2^n 种可能的结果，每种结果都需要 O(n) 时间来构建和比较，即使 n 约为 30，这也会变得天文数字般大。 

问题的结构表明了一种贪婪的方法，但困难在于仅比较两个端点是不够的。 正确的决定取决于删除一侧后哪个剩余间隔按字典顺序更小。 

关键的观察是，我们总是比较作为剩余间隔后缀的两个候选字符串。 我们可以通过用两个指针向内走来懒惰地比较它们，而不是完全具体化两者。 在每一步中，我们都会按字典顺序比较当前左右候选者，作为从一侧一致获取而形成的序列。 这种比较可以在不构造完整字符串的情况下完成。 

这就产生了一个策略：在每一步，决定从左还是右取是否会产生按字典顺序更小的剩余结构，并致力于该选择。 比较本身可能会将指针向内推进，直到发现差异。 

这将指数分支减少为线性扫描，并在整个过程中摊销偶尔的线性比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 最佳| O(n) 摊销 | O(1) 额外 | 已接受 |

 ## 算法演练

 我们维护两个指针，一个位于剩余区间的左端，一个位于右端。 在每一步中，我们决定是从左侧还是从右侧进行。

1. 初始化两个索引 l = 0 和 r = n - 1，以及一个空结果字符串。 这些指针代表当前可用的卡片间隔。 
2. 当l≤r时，我们考虑两个候选序列：一个从左边开始，一个从右边开始。 目标是决定哪种选择会导致字典顺序更小的最终结果。 
3. 为了比较这两个选项，我们使用临时指针 l2 = l、r2 = r 模拟“先行比较”。 我们贪婪地比较字符：如果 s[l2] 和 s[r2] 不同，我们立即知道哪一边更好； 否则，我们通过递增 l2 和递减 r2 向内移动。 
4. 如果在某个时刻左侧字符小于右侧字符，则从左侧获取会产生较小的字典结果，因此我们将 s[l] 附加到结果并递增 l。 
5. 如果右侧字符较小，则从右侧取，追加 s[r]，并递减 r。 
6. 如果我们耗尽比较而没有发现差异（剩余的段实际上是对称的），我们可以安全地从任一侧取； 我们始终如一地选择左翼以确保决定论。 
7. 重复此操作，直至消耗完所有字符。 

重要的部分是比较步骤。 这不是一个简单的恒定时间决策，但在整个过程中，每个指针移动在摊销意义上仅在每个位置发生一次。 

### 为什么它有效

 该算法保持不变，即在任何步骤中，剩余间隔表示部分构建结果的所有可能的延续。 当我们比较左优先和右优先结构时，我们正在比较由相同间隔的不相交但互补的遍历形成的两个按字典顺序排列的序列。 向内比较中的第一个不匹配决定哪个选择会导致较小的全局字符串。 因为字典顺序是在最早的不同位置决定的，所以一旦做出决定，未来的操作就无法在不与第一个不匹配相矛盾的情况下逆转它。 这保证了每个贪婪选择对于剩余后缀都是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = [input().strip() for _ in range(n)]
    
    l, r = 0, n - 1
    res = []

    while l <= r:
        i, j = l, r
        take_left = False

        while i <= j:
            if s[i] < s[j]:
                take_left = True
                break
            elif s[i] > s[j]:
                take_left = False
                break
            i += 1
            j -= 1

        if i > j:
            take_left = True

        if take_left:
            res.append(s[l])
            l += 1
        else:
            res.append(s[r])
            r -= 1

    sys.stdout.write("".join(res))

if __name__ == "__main__":
    solve()
```代码直接实现了两指针的构造。 内循环执行两个可能方向之间的字典顺序比较。 变量`take_left`对决策结果进行编码，一旦确定，我们就只消耗一个端点并缩小间隔。 

一个常见的微妙错误是忘记了相等的情况`i > j`，这意味着两侧直到剩下的中间部分都是相同的。 在这种情况下，任一选择都是安全的，但始终选择左侧可以避免歧义并确保确定性输出。 

另一个重要的细节是，我们直接将字符作为字符串进行比较，依赖于 Python 对单字符字符串的字典顺序，这与字母顺序相匹配。 

## 工作示例

 ### 示例 1

 输入：

 ABC

 我们从 l = 0、r = 2 开始。 

| 我| r | 比较 (i, j) | 决定| 结果 |
 | ---| ---| ---| ---| ---|
 | 0 | 2 | A vs C | A < C | 左转 |
 | 1 | 2 | B vs C | B < C | 左转 |
 | 2 | 2 | C | 只有一个| 左转 |

 结果变成ABC。 

该轨迹表明，当序列增加时，算法始终优先选择左侧，因为它会导致按字典顺序出现较早的较小字符。 

### 示例 2

 输入：

 乙乙乙

 开始 l = 0，r = 3。 

| 我| r | 比较 (i, j) | 决定| 结果 |
 | ---| ---| ---| ---| ---|
 | 0 | 3 | B 对 B，A 对 C | A < C | 左转 |
 | 1 | 3 | A vs B | A < B | 左转 |
 | 2 | 3 | C vs B | C > B | 向右走|
 | 2 | 2 | C | 只有一个| 左转 |

 结果变成A A B C。 

这个例子表明该算法在端点上并不是纯粹贪婪的。 即使 B 出现在右侧，更深入的比较表明，先向左走会导致最终的后缀更小。

 ## 边缘情况

 当所有剩余字符都相同时，向内比较永远不会发现差异，最终指针会交叉。 在这种情况下，算法始终从左侧进行选择。 例如，输入 A A A A 会产生重复的平局比较，直到 i > j，之后每次都会选择 left，产生 AAAA。 

当第一个不同的字符出现在间隔深处时，算法会正确地推迟决策，直到发现不匹配。 例如，B A A A C 与 C A A A B 会在决定性比较之前导致多个相等步骤，确保根据最早的词典差异而不是端点选择正确的一侧。
