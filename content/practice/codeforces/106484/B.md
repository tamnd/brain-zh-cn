 ## 解决方案
 ## 问题理解

 我们得到一个类似数字的参数`k`1 到 9 之间，以及一个位置`x`。 想象一下从 1 开始向上计数，但我们并不认为每个整数都是有效的。 一个数字只有满足至少两个条件之一才被“说出”：要么它能被`k`，或其十进制表示形式包含数字`k`。 我们使用这个规则在概念上过滤自然数，产生无限增加的“口头”数字序列。 任务是找出 的值`x`此过滤序列中的第 - 个数字。 

约束条件允许`x`高达 100,000，同时`k`是个位数。 这立即表明，如果每个数字的检查成本低廉，则任何检查每个整数可能达到数百万或更多的解决方案都是可以接受的，因为 100,000 个接受的元素通常需要扫描大约数十万到几百万个候选元素，具体取决于密度。 因此，直接模拟是可以实现的。 

主要的微妙之处在于过滤条件：检查“包含数字 k”必须以十进制形式仔细完成，而不是作为数字属性。 另一个边缘情况是由于两个条件可能重叠的事实而产生的。 例如，像 33 这样的数字，当`k = 3`既能被 3 整除，又包含数字 3，但在序列中只能计算一次。 如果一个幼稚的实现将每个数字的计数器增加两次，那么就会默默地过度计数。 

第二个潜在的陷阱是在计算时的误差一处理`x`- 第一个有效数字。 由于我们处理的是有效数字流而不是数组，因此当计数器等于时很容易返回当前候选值`x`不保证增量逻辑正确。 

## 方法

 暴力破解的想法很简单：从 1 开始，测试每个整数，并维护一个计数器，记录有多少数字满足规则。 对于每个整数`i`，我们检查是否`i % k == 0`或者是否为字符串形式`i`包含的字符表示`k`。 每当条件成立时，我们就会增加一个计数器。 一旦计数器达到`x`，我们返回当前整数。 

这是有效的，因为每个整数都被检查一次，并且过滤规则对于每个数字都是独立的。 这种方法的弱点是仅在常数因子意义上的性能：我们可能需要扫描超越`x`，因为有效数字不是均匀分布的。 例如，当`k = 9`，9的倍数和包含9的数字是比较频繁的，所以我们只扫描几十万个整数就可能达到10万个有效数字。 即使在最坏的情况下`k = 1`，几乎每个数字都是有效的，所以我们仍然只是粗略地扫描`x`数字。 这使得该方法在约束下足够有效。 

不需要更高级的组合优化或数字DP，因为我们不会被要求直接计数或跳转到答案，而只是枚举直到极限。

 ## 算法演练

 1.初始化一个计数器`cnt = 0`并开始迭代`i`从 1 向上。 我们需要顺序，因为定义取决于自然数的递增。 
2. 对于每个数字`i`，确定是否应包含在序列中。 首先检查是否`i % k == 0`。 这捕获了所有倍数`k`直接进行，无需数字处理。 
3. 如果尚未通过整除性包含在内，请检查数字是否包含在内`k`出现在`i`的十进制表示形式。 这可以通过转换来完成`i`到一个字符串并检查字符的成员资格`str(k)`。 
4. 如果任一条件成立，则递增`cnt`1。至关重要的是，即使两个条件都为真，每个数字仅发生一次此增量，因为序列仅对每个有效数字进行一次计数。 
5. 什么时候`cnt == x`,立即输出`i`并停止。 这保证了我们按升序返回第 x 个有效数字。 

### 为什么它有效

 该算法保持一个简单的不变量：处理完所有整数后`i`, 计数器`cnt`正好等于中的整数个数`[1, i]`满足该规则。 由于我们按升序扫描并且从不跳过候选者，所以第一次`cnt`达到`x`，当前的`i`恰好是最小的数，使得至少`x`有效数字≤`i`。 这与有序序列中第 x 个元素的定义匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    k, x = map(int, input().split())
    target = str(k)

    cnt = 0
    i = 0

    while True:
        i += 1
        if i % k == 0 or target in str(i):
            cnt += 1
            if cnt == x:
                print(i)
                return

if __name__ == "__main__":
    solve()
```实现遵循直接模拟策略。 变量`target`存储数字形式`k`所以我们避免重复地重新计算它。 循环递增`i`无限期地进行，直到达到所需的数量。 会员资格测试`target in str(i)`干净地捕捉数字条件。 

一个微妙的点是我们增加`cnt`每个仅一次`i`，即使两个条件都为真。 这`if`声明使用`or`，保证正确性。

 ## 边缘情况

 一个重要的边缘情况是当`k = 1`。 在这种情况下，每个数字都可以被 1 整除，因此整个序列就是自然数。 该算法立即处理这个问题：每次迭代都满足`i % 1 == 0`， 所以`cnt`每次递增，答案为`x`简直就是`x`。 

另一种情况是数字包含主导整除性。 例如，与`k = 9`，即使不能被 9 整除，像 19、29、39 这样的数字也都符合条件。模拟仍然有效，因为条件是一个简单的 OR，因此每个数字都会计算一次，无论有多少个原因使其有效。 

最后一个微妙的情况是重叠，例如`k = 3`和数字 33。该算法确保了正确性，因为 OR 条件可以防止重复计算。 尽管整除性和数字存在都是正确的，但计数器每个整数仅增加一次，从而保留了序列的精确结构。
