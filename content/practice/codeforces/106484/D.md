 ## 解决方案
 ## 问题理解

 我们得到一个从 1 到 n 的位置数组。 每个位置的行为就像一把锁，可以是空闲的，也可以是已经被某个查询锁定的。 最初每个职位都是免费的。 

每个查询描述从l到r的一段位置和两个开始时间，一个用于锁定，一个用于解锁。 在查询的锁定阶段，我们从左到右扫描其段，从 ts 开始每单位时间扫描一个位置。 当我们到达一个位置时，如果它当前是空闲的，我们将锁定它并将其分配给该查询。 如果它已被任何其他查询锁定，我们将保持不变。 解锁阶段稍后在时间 te 开始，并以相同的顺序再次扫描相同的段。 在此阶段，仅当该查询当前拥有该仓位时，该仓位才会被解锁； 否则什么也不会发生。 

所有查询的所有操作都放置在共享时间轴上。 如果同一位置同时发生多个操作，则按照查询索引的升序执行。 

对于每个查询，我们只关心它在锁定阶段成功锁定了多少个位置。 

关键的困难在于锁定是全局的并且是持久的，直到显式删除为止，因此较早或较晚的查询可能会根据时间重叠而相互阻塞。 

约束n，q ≤ 1000意味着操作总数约为q乘以段长度，最多约为100万次锁定更新和100万次解锁。 这排除了任何尝试以事件二次方的方式重新计算每个查询对或每个位置对的交互的解决方案。 对显式生成的事件进行模拟是可行的，但是尝试重复扫描时间步或重新计算每个查询的完整时间线的任何操作都会太慢。 

一个微妙的情况来自于同时进行的操作。 由于多个查询可能在相同的时间戳下对不同位置进行操作，因此按查询索引排序变得至关重要。 如果忽略此顺序，则后面的查询可能会错误地窃取或覆盖应在同一时间步中较早采取的锁定。 

## 方法

 直接解释一步一步地模拟时间。 对于每个整数时间，我们将检查所有查询，查看正在处理哪些位置，并更新状态。 然而，时间范围高达 10^9，因此随着时间的推移进行迭代是不可能的。 

更有用的观点是观察到没有任何东西取决于绝对时间，只取决于事件的相对顺序。 每个查询都会生成一系列独立操作：对其段中的每个位置进行锁定尝试，然后对相同位置进行解锁尝试。 每个此类操作都可以表示为带有时间戳的单个事件。 

这会将问题转换为所有事件的全局排序问题。 每个事件都是对特定位置的锁定尝试或解锁尝试。 仅当我们按时间递增顺序处理这些事件时，系统状态才会发生变化，并根据需要通过查询索引打破联系。 

一旦事件被排序，我们就按顺序模拟它们。 仅当仓位当时空闲时，锁定事件才会成功。 仅当该位置当前由该查询拥有时，解锁事件才会成功。 我们跟踪每个职位的所有权。 

这将问题从对连续时间的推理简化为对最多 2qn 个事件的离散扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（时间模拟）| O(最大时间 × q × 分段) | O(n) | 太慢了|
 | 事件排序+模拟| O(E log E) 其中 E ≤ 2qn | O(n + E) | 已接受 |

 ## 算法演练

 我们将每个查询转化为显式事件。

1. 对于每个查询，为其间隔内的所有位置生成锁定事件。 [l,r] 中位置 k 的事件时间为 ts + (k - l)。 这精确地模拟了顺序扫描。 
2. 对于每个查询，为其间隔内的所有仓位生成解锁事件。 事件时间为 te + (k - l)。 这反映了相同的从左到右的遍历，但开始时间较晚。 
3. 将每个事件存储为一个元组（time、query_id、type、position），其中type区分lock和unlock。 我们包含 query_id 是因为打破平局需要在时间匹配时首先处理较小的索引查询。 
4. 按时间字典顺序对所有事件进行排序，然后按 query_id 排序。 该类型不影响排序，因为该规则仅指定同时查询的顺序。 
5. 维护一个数组owner[pos]，最初为空。 还维护一个答案数组 ans[q]，最初为零。 
6. 按排序顺序处理事件。 如果事件是锁定尝试并且owner[pos]为空，则分配owner[pos] = query_id并递增ans[query_id]。 如果这是一次锁定尝试并且该位置已被拥有，则不执行任何操作。 
7. 如果事件是解锁尝试并且owner[pos]等于query_id，则清除owner[pos]。 否则什么都不做。 

这样做的关键原因是影响位置的每个动作都按时间顺序精确地表示一次。 任何后来的事件都不能追溯性地改变早期的决策，因为所有权只有在按时间顺序处理事件时才会更新。 当多个事件共享相同时间戳时，查询索引的平局可确保一致性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    
    events = []
    
    queries = []
    for i in range(q):
        ts, te, l, r = map(int, input().split())
        queries.append((ts, te, l, r))
        
        for k in range(l, r + 1):
            t_lock = ts + (k - l)
            t_unlock = te + (k - l)
            
            events.append((t_lock, i, 0, k))
            events.append((t_unlock, i, 1, k))
    
    events.sort()
    
    owner = [0] * (n + 1)
    ans = [0] * q
    
    for t, i, typ, pos in events:
        if typ == 0:
            if owner[pos] == 0:
                owner[pos] = i + 1
                ans[i] += 1
        else:
            if owner[pos] == i + 1:
                owner[pos] = 0
    
    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```该代码为每个查询的两个阶段构建完整的事件列表。 锁定事件标记为类型 0，解锁事件标记为类型 1。排序步骤通过正确的平局打破强制执行全局时间顺序处理。 

数组所有者存储当前持有每个位置的查询。 使用 0 作为“解锁”可以简化检查。 仅当锁转换成功时，答案数组才会递增，这与锁定阶段成功锁的定义完全匹配。 

一个微妙的点是，解锁事件仅在当前所有者与查询匹配时才适用，否则它们将被忽略。 这可以防止一个查询解锁另一查询的锁。 

## 工作示例

 考虑一个 n = 3 和两个查询的小场景。 

查询 1：ts = 1，te = 5，l = 1，r = 2

 查询 2：ts = 2，te = 4，l = 2，r = 3

 我们生成事件并对它们进行排序。 

| 时间 | 查询 | 类型 | 邮政 | 业主之前 | 行动| 业主后|
 | ---| ---| ---| ---| ---| ---| ---|
 | 1 | 1 | 锁| 1 | 无 | 锁| 1 |
 | 2 | 1 | 锁| 2 | 无 | 锁| 1 |
 | 2 | 2 | 锁| 2 | 1 | 跳过| 1 |
 | 3 | 2 | 锁| 3 | 无 | 锁| 2 |

 处理锁定事件后，查询1成功锁定2个位置，查询2锁定1个位置。 

此跟踪显示了同时查询排序如何防止查询 2 在时间 2 窃取位置 2，因为首先处理查询 1。

 ## 边缘情况

 一个关键的边缘情况是同一时间戳同时发生的事件。 例如，如果查询 1 和查询 2 在时间 2 都作用于同一位置，则查询顺序决定结果。 按查询索引排序可确保首先处理查询 1，因此如果它锁定位置，查询 2 将正确地将其视为已被处理。 

另一个边缘情况是解锁不影响外国所有权。 如果查询 2 解锁查询 1 当前拥有的仓位，则必须忽略该操作。 这是通过在清除所有权之前检查 Owner[pos] == query_id 来显式处理的，以防止意外的交叉查询干扰。 

最后的边缘情况是同一查询在锁定阶段重复访问同一位置。 由于所有权仅分配一次，并且后续的锁定尝试不会执行任何操作，因此每次成功获取（而不是每次访问）时，ans 的增量只会发生一次。
