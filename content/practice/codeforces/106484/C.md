 ## 解决方案
 ## 问题理解

 我们维护一个行为类似于普通 FIFO 结构的队列，但有一个额外的规则：每个值在任何时间最多只能出现一次。 可以存储的值是从1到m的整数，我们处理修改或查询该结构的Q操作。 

共有三个操作。 尝试在队列后面插入一个值，但只有当该值尚不存在时才会成功。 另一种是移除最前面的元素，这种操作总是有效的，因为这个操作出现时保证队列非空。 最后一个操作按从前到后的顺序询问当前队列中的第 x 个元素，如果该位置不存在，则答案为 -1。 

关键的微妙之处在于，我们没有被要求模拟任意容器，而是模拟具有唯一性约束和位置查询的序列。 约束 Q ≤ 10^6 和 m ≤ 10^6 排除了任何扫描队列或通过每个操作的线性搜索检查成员资格的方法。 即使单个 O(n) 操作重复 Q 次也会立即超出限制，因为在最坏的情况下队列大小可能会增长到 Q。 

一个幼稚的错误是将队列表示为 Python 列表并使用`x in list`以强制唯一性。 另一种方法是通过索引到列表来回答查询，但忘记从前面删除所有内容都会改变一切，从而使每次弹出的时间复杂度为 O(n)。 

当队列变大且查询频繁时，会出现具体的失败案例：

 输入：

 1 1

 1 1

 1 2

 1 3

 ...

 3 100000

 一个简单的基于列表的解决方案会重复扫描成员资格并在弹出时移动元素，从而导致超时。 

另一个微妙的错误是由于忽略唯一性而产生的：如果我们允许重复，对第一次出现位置的查询就会变得不明确并且偏离预期的模型。 

## 方法

 暴力模拟将队列保持为动态列表。 插入通过扫描整个列表来检查该值是否已经存在。 如果没有找到，则追加到末尾。 pop通过切片或者pop(0)删除第一个元素，直接查询索引。 

正确性很简单，因为它准确地反映了操作。 问题是性能。 成员资格检查的成本为 O(n)，并且由于移位而从前面弹出也成本为 O(n)。 由于 Q 高达 10^6 并且队列大小可能线性增长，总工作量变为 O(Q^2)，这远远超出了可行的限制。 

关键的观察是，我们实际上并不需要在变化的意义上维护“列表结构”。 我们只需要保留元素的相对顺序并支持三种操作：追加唯一元素、删除最旧的元素以及按当前顺序通过索引访问。 

这建议分离关注点：我们跟踪表示插入顺序的固定数组中的元素，并为前面维护一个移动指针。 我们不是物理地删除元素，而是推进头索引。 为了强制唯一性，我们维护一个布尔数组或哈希集，指示队列中当前值是否处于活动状态。 这将所有操作减少到 O(1)。 

队列成为阵列上的虚拟窗口，从而消除了所有昂贵的删除操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(Q^2) | O(Q^2) | O(Q) | 太慢了|
 | 最佳| O(Q) | O(Q) | 已接受 |

 ## 算法演练

 我们维护三个结构：一个数组`arr`按顺序存储插入的值，一个指针`head`标记当前的前面，以及一个布尔数组`in_queue`指示某个值当前是否位于活动队列窗口内。 

1. 对于值为 x 的插入操作，我们首先检查是否`in_queue[x]`是假的。 如果为假，我们将 x 附加到`arr`并标记`in_queue[x] = true`。 这可以确保唯一性，而无需扫描队列。 
2. 对于弹出操作，我们移动`head`向前直到我们跳过一个活动元素。 具体来说，我们将元素取为`arr[head]`，将其标记为不在队列中，并递增`head`。 这模拟了在 O(1) 摊销时间内删除前面的情况，因为每个元素都被删除一次。 
3. 对于要求第 x 个元素的查询操作，我们将实际索引计算为`head + x - 1`。 如果这个索引超出了当前数组的长度，我们输出−1。 否则，我们输出`arr[index]`。 原因是活动队列始终是已处理数组的连续后缀。 

为什么它起作用是基于以下不变量：每个元素要么已经被头指针永久跳过，要么仍然是活动后缀的一部分`arr`。 删除后没有元素重新进入结构，并且没有元素出现两次，因为我们维护严格的活动集标志。 因此，队列状态总是由段准确地表示`arr[head : len(arr)]`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    Q, m = map(int, input().split())
    
    arr = []
    in_queue = [False] * (m + 1)
    head = 0
    
    out = []
    
    for _ in range(Q):
        tmp = input().split()
        t = int(tmp[0])
        
        if t == 1:
            x = int(tmp[1])
            if not in_queue[x]:
                arr.append(x)
                in_queue[x] = True
        
        elif t == 2:
            x = arr[head]
            in_queue[x] = False
            head += 1
        
        else:
            x = int(tmp[1])
            idx = head + x - 1
            if idx >= len(arr):
                out.append("-1")
            else:
                out.append(str(arr[idx]))
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现将所有插入的值存储在一个不断增长的数组中，并且永远不会从左侧物理删除。 这`head`指针取代了昂贵的双端队列弹出。 布尔数组保证插入时的成员资格检查为 O(1)，因此永远不会添加重复项。 

一个微妙的一点是我们从不退缩`arr`。 这是故意的：即使旧元素保留在内存中，它们也会被忽略一次`head`通过他们。 查询仅依赖于索引算术，而不依赖于结构突变。

 | 测量 | 复杂性 | 说明|

 | 时间 | O(Q) | 每个元素插入一次，删除一次，并在 O(1) | 中查询。

 ## 边缘情况

 一种重要的边缘情况是重复插入相同的值而不删除。 例如：

 输入：```
1 5
1 1
1 1
1 1
3 1
```该算法仅保留值 1 的一个实例，因为`in_queue[1]`阻止所有重复。 队列状态是`[1]`，因此查询返回 1。 

另一个边缘情况是在多次弹出后查询超出当前大小：

 输入：```
1 3
1 1
1 2
2
3 2
```流行之后，仅`[2]`遗迹。 查询第二个元素计算`head + 1`，这超过了`len(arr)`，所以答案是-1。 基于指针的表示确保我们永远不会访问无效内存； 纯粹以算术方式检查边界。 

最后的边缘情况是最大输入压力，其中所有操作都是插入，然后是查询。 由于没有物理删除，因此数组会增长，但在 O(Q) 内存中保持有效，并且所有查询都会在恒定时间内得到解决。
