 ## 解决方案
 ## 问题理解

 我们有一个分层的防御网格。 无人机从底排的某个位置开始，一次向上移动一排。 从`(r, c)`它可能会去`(r - 1, c - 1)`,`(r - 1, c)`， 或者`(r - 1, c + 1)`只要目的地在棋盘内且未被阻挡即可。 

每次移动后，我们最多可能永久添加一个新障碍。 新障碍物必须放置在无人机当前行上方的一排或两排。 

如果无人机到达第一排，则无人机获胜。 如果在某个时候它没有合法的举动，我们就赢了。 

有趣的部分是交互器是自适应的。 无人机不遵循固定路径。 我们的策略必须在每一个合法的行动序列中取得成功。 

板的尺寸最多为`100 × 100`，对于状态空间动态规划解决方案来说足够小。 困难不在于网格大小，而在于正确地建模游戏。 

关键的观察是障碍物只能放置在无人机上方接下来的两排中。 这种限制极大地限制了未来重要信息的数量。 

一个常见的错误是认为我们必须记住我们曾经设置的每一个障碍。 一旦无人机从它们下面经过，它们中的大多数就变得无关紧要了。 游戏状态可以被更积极地压缩。 

另一个容易犯的错误是将无人机路径视为固定的。 交互者选择任何合法的举动，因此过渡必须是对抗性的。 

考虑这个小例子：```
3 3
...
...
...
```假设无人机位于`(3, 2)`。 

阻塞`(2, 2)`不会强迫无人机进入`(2, 1)`或者`(2, 3)`。 交互者可以选择其中之一。 任何正确的解决方案都必须考虑到所有法律反应。 

当我们在前面两排放置障碍物时，就会出现第二种微妙的情况。 只有在无人机采取下一步行动后，该障碍才可能变得相关。 忘记将该信息带入下一个状态会导致错误的转换。 

## 方法

 暴力游戏搜索会将整个网格以及所有新插入的障碍物存储在一起。 从每个位置，我们都会尝试每个可能的障碍物放置，然后每个合法的无人机移动，然后递归。 

这种方法是正确的，但是状态空间爆炸了。 每一次转弯都可能会产生新的永久性障碍，因此棋盘配置的数量呈指数级增长。 

关键的观察是，放置限制限制了未来信息的保存量。 

当无人机在行时`i`，之前插入的唯一仍能影响未来游戏的障碍是已经排成一排的障碍`i - 1`。 

为什么只有一个？ 

较早放置的障碍物只能插入无人机前方一排或两排。 当无人机到达行时`i`，任何较旧的插入障碍物要么已经位于无人机下方并且不相关，要么恰好位于无人机上方的一排。 这样的“预载”障碍永远不会超过一个。 

这使国家急剧崩溃。 我们不需要记住整个历史，我们只需要知道：`(row, column, status_of_row_above)`。 

官方的解决方案正是使用了这种压缩。 该状态记录无人机位置以及紧邻上方的行是否已包含先前插入的障碍物，如果是，则三个可达列中的哪一列包含该障碍物。 

这只产生`O(nm)`状态，每个状态都有固定数量的转换。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 太慢了|
 | 最佳 DP/游戏 DP | O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 官方解决方案定义了一个游戏 DP，每个单元有四种变体。 压缩来自这样一个事实：之前插入的至多一个障碍仍然很重要。 

1. 定义`dp[i][j][s]`。 

目前无人机处于`(i, j)`。`s = 0`表示该行中没有先前插入的障碍物`i - 1`。`s = 1, 2, 3`表示之前插入了一个障碍物`(i - 1, j - 1)`,`(i - 1, j)`， 或者`(i - 1, j + 1)`分别。 
2. 将值解释为游戏状态。 

如果一个州仍能在最佳防御下到达顶排，那么它就赢得了无人机。 

如果防御者能够强行拦截，那么一个州就会在无人机方面失败。 
3. 初始化基行。 

行中已有的任何状态`1`无人机之所以获胜，是因为它已经取得了突破。 
4. 从上到下处理行。 

由于移动总是减少行索引，因此游戏图是 DAG。 
5. 列举防守者的动作。 

防守方可以将新的障碍物放置在行中`i - 1`或在行中`i - 2`。 

只有固定数量的展示位置才有意义。 

对于行`i - 1`，只有无人机的三个候选目的地很重要。 

对于行`i - 2`，只有五列可以影响下一个状态。 官方解决方案明确列举了这些恒定大小的可能性。 
6. 列举无人机的反应。 

防守方选择位置后，无人机可以选择任何合法的向上移动。 

这种转变是对抗性的：

 防御者希望无人机所得到的每个状态都会失败。 

无人机只需要一次获胜的延续。 
7. 记录一次成功的移动。 

每当防御者的动作将无人机获胜状态转变为无人机失败状态时，存储该动作。 

官方解决方案直接根据这些记录的转换重建交互策略。 

### 为什么它有效

 不变的是，每个与未来相关的插入障碍都在状态内部表示。 

过去的任何事情都不能影响未来的比赛。 

一旦建立了压缩，游戏就变成了有限 DAG 游戏。 每一次转换都与一个合法的防守者动作完全匹配，然后是一个合法的无人机动作。 标准极小极大推理适用。 

如果存在一个位置，使得每个合法的无人机响应都进入防御者获胜状态，则该状态将为防御者获胜。 如果每个防守者的位置至少留下一个获胜的延续，那么一个州就赢得了无人机。 

由于 DP 会评估所有这些可能性，因此它会计算出正确的游戏结果。

 ## 边缘情况

 之前插入的障碍物可能仍然存在于无人机正上方的一排中。 DP状态明确记录该信息。 如果没有它，解算器可能会错误地允许移动到之前被阻止的单元格中。 

站在左边界或右边界附近的无人机的候选动作少于三个。 在评估极小极大结果之前，转换生成器必须丢弃超出范围的列。 

防守者放置在前面两排不会影响当前的移动。 它仅更改下一个状态的描述符。 混合这两种效果是错误的常见来源，这就是为什么压缩状态明确地将未来的障碍向前推进。
