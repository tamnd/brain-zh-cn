 ## 解决方案
 ## 问题理解

 我们得到一个有向加权图，其中两个旅行者从相反的两端开始：一个从节点 1 开始，另一个从节点 n 开始。 如果正常行走，每条边都会有耐力消耗。 除了步行之外，还可以选择沿着边缘“滑行”：支付一个单位的共享预算可以完全消除该边缘的耐力成本。 

两名旅客独立行动，可以自由选择何时使用出租车。 两者的出租车使用总数不能超过 w。 他们的目标是在某个节点相遇，我们希望在最佳使用预算后最大限度地减少两个旅行者所花费的总体力。 

输入描述了多个测试用例。 每个测试用例都给出了一个图表，在所有测试中总共有大约一千个节点和边，预算 w 最多为 1000。边权重可能很大，但由于它们只是添加或删除，所以问题的结构是由选择用于折扣的边数而不是算术复杂性驱动的。 

一种天真的解释是，我们选择两条路径，一条从 1 到某个相遇节点 v，一条从 n 到同一个 v，然后决定使用最多 w 个优惠券使这些路径上的哪些边免费。 

如果人们假设最好的策略总是独立地采用最短路径，然后贪婪地应用优惠券，那么就会出现一个微妙的问题。 但这会失败，因为路径的选择取决于我们计划折扣的边。 即使重边增加了基本路径长度，也可能值得通过，因为如果选择优惠券，它就会变得免费。 

第二个不明显的失败案例是假设我们应该始终将优惠券应用于图中全局最大的边。 这是不正确的，因为只有在所选路径中实际使用的边才有资格享受折扣。 

## 方法

 暴力策略会尝试枚举从 1 到每个节点以及从 n 到每个节点的所有可能路径，并且对于每对路径，通过选择两条路径上的最大边权重来计算应用最多 w 个优惠券的最佳方式。 即使我们将自己限制在简单路径上，可能的路径数量也会以 n 为指数，使得这种方法不可行。 

关键的结构观察是，一旦两条路径和相遇节点固定，优惠券的效果就变得与排序无关：每个使用的优惠券只是将任一路径上的一个选定边缘变成零成本。 因此，对于固定路径，我们只关心沿它们的边权重的多集。 

这建议将问题重新构建如下：我们不是在修复路径后明确选择要折扣的边，而是将优惠券的使用合并到路径状态本身中。 对于一条路径，我们跟踪到目前为止我们已经使用了多少优惠券，并为每条边决定是花费优惠券还是正常支付其耐力成本。 

这将每个单源问题转换为扩展状态空间上的最短路径问题，其中状态是由节点和已使用的优惠券数量组成的对。 

我们从节点 1 运行这条动态最短路径，以获得使用所有可能数量的已用优惠券到达每个节点的最佳成本，并从节点 n 执行相同的操作。 然后我们尝试每一个可能的会面节点，并在两个旅行者之间分配预算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 枚举路径并随后分配优惠券 | 指数| 指数| 太慢了|
 | 具有优惠券计数的状态扩展最短路径 | O((n + m) · w) | O((n + m) · w) | O(n·w) | O(n·w) | 已接受 |

 ## 算法演练

 我们独立对待每个测试用例。

1. 我们构建一个图及其反转版本。 反转图用于计算距节点 n 的距离，就好像它是源一样，因为对于该计算，边必须是可向后遍历的。 
2. 我们为前向过程定义一个距离表，其中 dp1[v][k] 表示在恰好使用了 k 个优惠券的情况下从节点 1 到达节点 v 的最小耐力成本。 这种状态是必要的，因为可以用不同的剩余预算分配来到达同一节点，并且这些会导致不同的未来可能性。 
3. 我们初始化 dp1[1][0] = 0 并将所有其他状态初始化为无穷大。 然后，我们在状态（节点、已用优惠券）上运行最短路径过程。 沿着边 u → v 且成本为 z 的转换有两种工作方式。 如果我们不使用优惠券，我们会从 dp1[u][k] 移动到 dp1[v][k]，并增加成本 z。 如果我们使用优惠券并且 k + 1 ≤ w，我们就会从 dp1[u][k] 移动到 dp1[v][k + 1]，而不会增加成本。 
4. 我们从反转图上的节点 n 开始重复相同的过程，生成 dp2[v][k]，它表示使用 k 个优惠券从 n 到 v 的最佳成本。 
5. 对于每个节点 v，我们尝试两个旅行者之间的所有预算分配。 如果第一个使用 k 个优惠券，第二个使用 t 个优惠券且 k + t ≤ w，则总成本为 dp1[v][k] + dp2[v][t]。 我们取所有 v 和所有有效分割的最小值。 
6. 如果任何节点都没有可达状态，则答案为-1。 

这种方法有效的关键原因是，优惠券的使用完全是本地的边缘，并且除了通过全局计数约束之外，不会在路径的不同部分之间交互。 通过将优惠券计数嵌入到状态中，我们保留了最佳子结构：使用 k 个优惠券到达节点的最佳方式仅取决于具有兼容优惠券使用的早期最佳子路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    T = int(input())
    for _ in range(T):
        n, m, w = map(int, input().split())
        g = [[] for _ in range(n + 1)]
        rg = [[] for _ in range(n + 1)]

        for _ in range(m):
            x, y, z = map(int, input().split())
            g[x].append((y, z))
            rg[y].append((x, z))

        def dijkstra(source, graph):
            dp = [[INF] * (w + 1) for _ in range(n + 1)]
            dp[source][0] = 0

            import heapq
            pq = [(0, source, 0)]

            while pq:
                dist, u, k = heapq.heappop(pq)
                if dist != dp[u][k]:
                    continue

                for v, z in graph[u]:
                    if dp[v][k] > dist + z:
                        dp[v][k] = dist + z
                        heapq.heappush(pq, (dp[v][k], v, k))

                    if k < w and dp[v][k + 1] > dist:
                        dp[v][k + 1] = dist
                        heapq.heappush(pq, (dist, v, k + 1))

            return dp

        dp1 = dijkstra(1, g)
        dp2 = dijkstra(n, rg)

        ans = INF
        for v in range(1, n + 1):
            for k in range(w + 1):
                if dp1[v][k] == INF:
                    continue
                for t in range(w - k + 1):
                    if dp2[v][t] == INF:
                        continue
                    ans = min(ans, dp1[v][k] + dp2[v][t])

        print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```该实现在扩展状态上使用优先级队列。 每个状态存储当前节点以及到目前为止已使用的优惠券数量。 关键的实现细节是，每条边都会产生两种松弛：一种不消耗优惠券并根据边权重增加成本，另一种消耗优惠券并在增加优惠券数量的同时增加零成本。 

一个常见的错误是忘记优惠券的使用会改变状态维度，这意味着使用不同的 k 值重新访问同一节点是至关重要的。 将 dp 压缩为每个节点的单个阵列将失去最佳解决方案。 

## 工作示例

 考虑一个小图，其中节点 1 以成本 5 连接到 2，节点 2 以成本 5 连接到 3，节点 n 为 3。假设 w = 1。 

从节点 1，我们可以通过两种可能性到达节点 3：没有优惠券产生成本 10，在任一边缘使用一张优惠券产生成本 5。节点 3 的 dp 表反映了这两种状态。 

从节点 3 回到自身，dp2[3][0] = 0。 

| 步骤| 节点| 使用优惠券 | 成本|
 | ---| ---| ---| ---|
 | 开始| 1 | 0 | 0 |
 | 1→2 正常 | 2 | 0 | 5 |
 | 2→3 优惠券 | 3 | 1 | 5 |

 此跟踪显示分割优惠券使用如何改变可达到的成本。 

现在考虑具有两个会议选项的第二个示例。 如果节点 1 同时连接到 2 和 3，并且两者都以不同的权重连接到 n，则算法会正确地独立评估两个相遇节点并组合前向和后向状态。

 ## 边缘情况

 一种极端情况是，两名旅客都受益于将所有优惠券集中在集合点的一侧。 该算法可以处理此问题，因为分割循环允许一侧 k = 0 到 w，并在另一侧独立进行补偿。 

另一个边缘情况是最佳路径根据优惠券使用情况而变化。 只有当优惠券可用时，直接的高成本优势才可能成为最佳选择。 这是正确处理的，因为 DP 允许通过不同的优惠券计数到达同一节点，从而有效地编码同一位置的不同“版本”。 

最后的边缘情况是断开的图，其中前向或后向 DP 永远不会到达节点。 这些状态仍然是无限的，并且在计算最终最小值时自然会被忽略，当不存在有效的交汇点时会产生 -1。
