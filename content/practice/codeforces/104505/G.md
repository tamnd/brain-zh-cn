 ## 解决方案
 ## 问题理解

 我们得到了一系列按固定顺序玩的关卡。 一开始，英雄拥有一些初始力量，每个级别都有两个怪物可用。 玩家每关必须选择一只怪物，唯一的限制是所选怪物的力量不能超过英雄当前的力量。 

击败怪物后，英雄的力量会增加该怪物的力量。 这会产生一个反馈循环：尽早选择较弱的怪物可能会阻止以后解锁更强的选择，而如果当前力量太小，则可能不可能选择更强的可用怪物。 

任务不是计算最终的力量或最佳分数，而只是确定可行性：是否存在任何选择序列（每个级别一个），使英雄能够按顺序生存所有级别。 

约束允许最多 2000 个级别，值最多为 10^6。 对选择进行简单的指数搜索会立即变得太大，因为每个级别都会分为两种可能性，导致 2^n 条可能的路径，这远远超出了任何可行的计算。 

当局部更强的怪物阻止未来的可访问性时，贪婪直觉的微妙失败案例就会出现。 例如，如果早期选择一个大型怪物会导致后面的关卡变得不可能，因为两个怪物都超过了剩余力量，那么贪婪的“总是选择最强的”策略可能会失败。 相反，总是采用最弱的可能也可能会失败，因为它可能无法增加足够的力量来解锁未来的选择。 

因此，困难在于跟踪每个级别后所有可达到的功率状态，同时避免指数爆炸。 

## 方法

 暴力方法将其视为分层图中的路径搜索。 每一层对应一个等级，每种状态都是一种可能的英雄力量。 从级别 i 具有 x 能力的状态，我们可以通过选择怪物 a_i 或 b_i 过渡到级别 i+1，前提是它≤ x，并且新状态变为 x + a_i 或 x + b_i。 

这立即表明 BFS 或 DFS 优于状态。 问题在于不同功率值的数量快速增长。 在最坏的情况下，每个选择都会创建一个新的不同总和，因此在 i 个级别之后，我们可能有 O(2^i) 状态。 当 n = 2000 时，这是完全不可行的。 

关键的观察是，虽然序列的数量是指数级的，但可达功率值的结构具有很强的单调性：对于固定级别，如果某个功率可达，则所有较小的功率也被有效控制，无需单独跟踪。 这使我们能够将状态空间压缩为每个级别之后的最大可达功率，或者更准确地说，一组可以简化为单个贪婪边界的“最佳代表”。 

在每个级别，我们不需要跟踪所有可能的权力。 到目前为止，我们只关心可达到的最大功率，因为​​任何功率较小的状态都无法解锁最大状态在同一级别也无法解锁的任何东西。 由于转换只需要检查可行性（x ≥ a_i 或 b_i），因此该过程简化为维持一个值：处理每个级别后的最佳可能当前功率，假设我们总是选择最佳可行选项。 

每个级别的决策变得简单：在a_i和b_i中，我们取≤当前功率的最大值。 如果两者都不可行，我们就会失败。 

这种贪婪之所以有效，是因为与选择较小的怪物相比，选择较大的可行怪物永远不会减少未来的选择。 两种选择都会消耗一个级别，但较大的选择会更严格地增加或保留未来可达到的阈值。

## 算法演练

 我们按顺序处理级别，同时维护单个变量`power`，代表我们在当前等级下可以达到的最大英雄强度。 

1. 初始化`power = f`，起始强度。 这代表了做出任何决定之前的最佳状态。 
2.对于从1到n的每个级别i，检查两个怪物`a_i`和`b_i`。 
3.检查两个怪物中哪一个可以被击败，即它们的力量≤当前`power`。 
4. 如果两个怪物都无法击败，则立即断定游戏无法完成。 
5. 如果只有一个怪物是可击败的，则选择它并将其力量添加到`power`。 
6. 如果两者都可以击败，则选择较大的一个。 这最大限度地增加了`power`以相同的成本消耗一个级别，确保未来没有劣势。 
7. 成功处理完所有关卡后，输出游戏可以完成。 

### 为什么它有效

 该过程依赖于这样一个事实：在任何级别，只有当前可实现的最大功率才重要。 如果两个国家处于同一水平，则权力较高的国家将支配另一个国家，因为未来的每一个约束都是“权力必须至少达到某个阈值才能继续进行”的形式。 由于转换只会增加功率，因此较高的电流值永远不会降低未来的可行性。 因此，仅保持最大可达功率就足够了，并且贪婪地选择最大的可行怪物会在每一步中保留该最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, f = map(int, input().split())
    power = f

    for _ in range(n):
        a, b = map(int, input().split())

        can_a = a <= power
        can_b = b <= power

        if not can_a and not can_b:
            print("N")
            return

        if can_a and can_b:
            chosen = max(a, b)
        else:
            chosen = a if can_a else b

        power += chosen

    print("S")

if __name__ == "__main__":
    solve()
```该解决方案保持单一运行值`power`并逐级更新。 关键的实现细节是我们在选择之前总是检查可行性，确保我们永远不会添加无效的怪物。 当两个选择都有效时，我们明确地取最大值以最大化未来的可达性。 

检查的顺序很重要：我们必须在尝试挑选怪物之前检测到失败情况。 否则，无效的添加可能会错误地增加功率并掩盖不可能性。

 ## 边缘情况

 一个关键的边缘情况是两个怪物的力量完全等于当前力量。 该算法仍必须将其视为有效并允许选择。 例如：

 输入：```
2 3
3 3
3 3
```在第 1 级，两者都是可行的，因此我们选择 3 中的一个并将功效增加到 6。在第 2 级，两者都是可行的，我们成功了。 贪心规则并不重要，因为两个选择是相同的。 

另一个边缘情况是立即死锁：

 输入：```
1 2
3 3
```在唯一的级别上，两个怪物都超过了力量，因此在任何更新之前检查都会正确触发失败。 

第三种微妙的情况是，一个怪物可行但较小，而另一个则不可行：

 输入：```
1 5
2 10
```只有 2 个有效，所以我们必须选择它。 在不检查可行性的情况下选择 max 会错误地选择 10 并错误地接受该情况。 采取 max 之前的可行性检查对于正确性至关重要。
