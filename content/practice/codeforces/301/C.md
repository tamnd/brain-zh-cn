 ## 解决方案
 ## 问题理解

 我们必须构造一个小的字符串重写程序。 该程序由有序命令组成。 每个命令都会搜索一个子字符串并用另一个字符串替换它第一次出现的位置。 有些命令在替换后继续执行，而其他命令则立即终止。 

一般来说，任务不是增加每个整数。 我们只需要一个适用于给定数字集的程序。 每个输入数字最多为 1024，因此总共最多有 1025 个可能的值。 50 个命令的限制比输入大小本身的限制要严格得多。 

关键细节是如何选择命令。 在每次迭代期间，算法从上到下扫描命令并执行左侧出现在当前字符串中某处的第一个命令。 这意味着命令顺序完全决定行为。 意外匹配另一个数字的命令可能会阻止预期命令的运行。 

命令中的字符串可以包含数字和字符`?`。 该语句从未给出通配符语义`?`，因此它的行为与正常字符相同。 由于所有输入数字仅包含数字，因此任何包含`?`左侧永远不会匹配。 最简单的解决方案忽略`?`完全。 

限制很小。 我们最多只有 100 个数字，每个数字都低于 1025，并且只允许 50 个命令。 即使所有数字之间的二次检查也是微不足道的。 这一挑战纯粹是建设性的：设计交互互不干扰的命令。 

一种简单的方法是为每个数字创建一个命令：```
x<>x+1
```对于样品`{10, 79}`，这有效：```
10<>11
79<>80
```但是，一旦一个数字是另一个数字的子串，这种方法就会失败。 假设集合是：```
1
10
```如果我们放置：```
1<>2
10<>11
```然后输入`10`执行第一个命令，因为`1`出现在里面`10`。 结果变成`20`，这是错误的。 

颠倒顺序也失败：```
10<>11
1<>2
```现在输入`10`变成`11`，但算法继续，第二个命令再次匹配，产生`22`。 

不明显的危险是替换可能会产生新的匹配。 我们必须保证在预期的转换之后，不会触发任何后续命令。 

另一个微妙的情况是子串链：```
1
10
100
```不小心的排序很容易重写`100`通过几个意想不到的中间状态。 

这个问题变成了避免模式之间冲突的仔细练习。 

## 方法

 蛮力的想法很简单。 对于每个输入数字`x`，添加终止命令：```
x<>x+1
```如果没有数字是另一个数字的子串，则这是立即正确的。 第一个匹配命令唯一标识输入并在替换后终止。 

当一个数字出现在另一个数字内部时，就会出现问题。 由于命令是针对子字符串进行全局检查，而不是针对整个字符串，因此较短的模式可能会劫持较大的数字。 

一种可能的强力修复是引入临时标记字符和多个重写阶段。 例如，我们可以先用特殊符号标记特定的数字，然后将标记转换为最终答案。 由于命令字符串可能包含`?`，此字符可以充当从未出现在原始输入中的私有标记。 

这个方向有效，但变得混乱。 我们需要仔细管理临时状态、命令排序和清理之间的交互。 命令的数量也会快速增长。 

关键的观察结果是域非常小。 每个输入的数字都小于1025，因此其十进制长度最多为四位数字。 更重要的是，可能的原始字符串只有 1025 个。 

我们可以使用经典的 trie 风格的想法，而不是直接对抗子串碰撞。 如果我们在较短的字符串之前处理较长的字符串，那么只要较短的数字是较长的数字的子字符串，较长的数字就会优先。 

这仍然不能解决所有问题，因为替换更长的数字后，结果可能包含另一种模式。 关键的改进是使每个命令终止，使用`<>`。 一旦发生预期的替换，执行立即停止。 以后的命令都不能干预。 

现在正确性降低到一个条件：

 对于每个输入数字`a`，在所有左侧出现在里面的命令中`a`，正确的命令为`a`必须是第一位的。 

这很容易保证。 我们通过减少字符串长度对数字进行排序。 如果两个数字具有相同的长度，则除非它们相同，否则两个数字都不能是另一个数字的子串。 由于输入代表一个集合，因此重复并不重要。 

按长度递减排序后，每个数字自己的命令出现在可在其内部匹配的所有较短子字符串的命令之前。 

一旦与正确的顺序配对，强力构造就会再次有效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 简单的无序命令 | O(n²) 验证 | O(n) | 错误|
 | 长度排序的终止命令 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 将所有数字读取为字符串。 
2. 如有必要，删除重复项。 不需要多个相同的命令。 
3. 按长度递减顺序对字符串进行排序。 
4. 对于每个字符串`s`，创建一个终止命令：```
s<>str(int(s)+1)
```1. 按顺序输出命令。 

排序步骤就是整个技巧。 假设一个数字`a`包含另一个数字`b`作为子串。 然后`|b| < |a|`，因为相同长度的不同字符串不能互相成为子串。 由于我们首先处理较长的字符串，因此命令`a`出现在命令之前`b`。 

输入时`a`被处理后，其自身的命令是最早匹配的命令。 替换使用`<>`，因此执行立即停止。 没有更小的子字符串命令有机会运行。 

### 为什么它有效

 考虑任何输入字符串`x`。 

它自己的命令显然匹配，因为`x`包含自身作为子字符串。 

现在考虑任何也可以匹配的早期命令`x`。 由于命令是按长度递减排序的，因此任何较早的命令都对应一个长度至少为`|x|`。 

不同的较长字符串不能是以下字符串的子串`x`。 不同的等长字符串也不能是以下字符串的子串`x`。 唯一等长子串`x`是`x`本身。 

所以第一个匹配的命令必须恰好是`x`。 

该命令替换`x`和`x+1`并立即终止，因为它使用`<>`。 

因此，每个输入数字都会转换为其后继数字，并且不会执行任何意外命令。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    nums = []
    seen = set()
    
    for _ in range(n):
        s = input().strip()
        if s not in seen:
            seen.add(s)
            nums.append(s)
    
    nums.sort(key=lambda x: (-len(x), x))
    
    ans = []
    
    for s in nums:
        t = str(int(s) + 1)
        ans.append(f"{s}<>{t}")
    
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```实现很短，因为一旦理解了排序参数，构造本身就很简单。 

我们将数字存储为字符串，因为子字符串的行为取决于它们的文本表示，而不是它们的数值。 过早将它们转换为整数会丢失前导零结构，尽管这个问题保证了标准十进制表示法中的正整数。 

如果保证输入是一个集合，则重复删除在技术上是可选的，但保留它可以使构造更清晰并避免重复的命令。 

排序关键是关键行：```
nums.sort(key=lambda x: (-len(x), x))
```我们按长度递减排序。 二级词典顺序与正确性无关，但提供确定性输出。 

每个命令都使用`<>`， 不是`>>`。 这种微妙的选择可以防止在正确的转换已经发生后进行级联重写。 

替换字符串很简单`int(s) + 1`，转换回十进制形式。

import io

def solve():

    backup_stdout = sys.stdout

 ## 边缘情况

 考虑输入：```
2
1
10
```生成的命令是：```
10<>11
1<>2
```执行于`10`收益如下：

 该算法从上到下检查命令。`10<>11`立即匹配，所以`10`变成`11`并终止执行。 危险的较短模式`1`从不执行。 

现在考虑：```
3
1
10
100
```命令是：```
100<>101
10<>11
1<>2
```输入`100`包含两者`10`和`1`作为子字符串，但它自己的命令首先出现，因为它最长。 替换会立即终止，因此较短的命令永远不会触发。 

另一个微妙的情况是等长字符串：```
2
12
21
```两个字符串都不能是另一个字符串的子字符串，因为它们具有相同的长度并且不同。 任何订购都有效。 生成的命令可能是：```
12<>13
21<>22
```输入`12`仅匹配第一个命令，而输入`21`仅匹配第二个。 

最后，考虑边界值：```
1
1024
```生成的命令是：```
1024<>1025
```该问题允许输出大于 1024。只有原始输入是有界的。 该结构通过普通整数加法自然地处理这个问题。
