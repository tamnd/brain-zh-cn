 ## 解决方案
 ## 问题理解

 我们有一组放置在二维网格上的站点。 在任何两个车站之间移动所需的时间与曼哈顿距离乘以常数因子成正比$d$。 各站$i$（第一个和最后一个除外）提供一次性奖励，使我们的可用时间增加$a_i$。 我们从站点 1 开始，使用少量的正时间，也可以仅在站点 1 以每单位时间 1 的固定成本购买额外的时间。 

任务是确定我们必须在车站 1 花费的最低金额，以便我们可以从车站 1 出发并最终到达车站$n$计时器不会达到零。 

从根本上来说，这是一个有变化的最短路径问题：边缘成本取决于参数（时间限制），我们可以通过收集奖金或购买额外的初始时间来增加该参数。 

约束条件$n \le 100$立即建议$O(n^3)$甚至$O(n^2 \log n)$方法是可以接受的。 所有货币对的完整图表仅是$10^4$边，因此最短路径计算是可行的。 尝试枚举所有可能访问的站点子集是不可行的，因为这会呈指数级增长。 

一个微妙的点是，时间不仅仅是边缘消耗的资源，它也在节点上增加，并且可以通过金钱部分控制。 这使得天真的最短路径公式不正确，除非我们仔细地将“可用时间预算”整合到状态或可行性检查中。 

边缘情况出现在以下情况：

 从 1 到 n 的直接路径在几何上是存在的，但如果没有中间站，这是不可行的，即使这些站从纯粹的距离意义上来说从来都不是最佳的访问方式。 另一个问题是，较早收集奖励站会增加后来长边的可行性，这意味着不考虑资源增益的最短路径会失败。 

## 方法

 一个蛮力的想法是将每个站点子集视为一组可能收集的奖金，并尝试计算我们是否可以到达站点$n$仅使用这些奖金加上初始资金。 对于每个子集，我们可以在具有固定能量容量的图上运行 Dijkstra 或 BFS。 然而，这需要$O(2^n)$子集，每个子​​集至少花费$O(n^2 \log n)$，这是完全不可行的。 

关键的观察是我们不需要明确地决定哪个子集是最佳的。 相反，我们可以二分查找答案：钱的多少决定了最初的时间预算。 对于固定的初始预算，我们只需要检查是否到达车站$n$一路上收集奖金是可能的。 

这种可行性检查可以使用 Dijkstra 来完成，其中州政府跟踪到达每个站点的最大剩余时间。 每当我们穿过一条边时，我们都会减去旅行成本。 当我们到达一个车站时，我们会添加一次它的奖励。 

重要的结构见解是单调性：如果我们能到达车站$n$有一些初始资金$X$，那么我们也可以用任何方法达到它$X' > X$。 这允许对答案进行二分搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集+最短路径|$O(2^n \cdot n^2 \log n)$|$O(n^2)$| 太慢了|
 | 二分查找+Dijkstra可行性|$O(n^2 \log n \log V)$|$O(n^2)$| 已接受 |

 ## 算法演练

 我们首先预先计算所有成对的曼哈顿距离并乘以$d$。 这给了我们一个完整的加权图。 

1. 定义一个函数`can(X)`检查我们是否可以到达车站$n$从初始时间开始$X$在1号站。 
2. 内部`can(X)`，我们使用优先级队列（最大堆），其中每个状态是`(remaining_time, node)`。 我们从`(X, 1)`。 
3.维护数组`best[i]`代表我们在车站达到的最长剩余时间$i$。 只有当状态提高了该值时，我们才会扩展它。 这避免了多余的探索。 
4.当我们弹出一个状态时`(t, u)`，我们考虑所有邻居$v$。 旅行费用是$cost(u, v)$。 如果$t \ge cost(u, v)$，我们可以移动到$v$与剩余时间$t - cost(u, v)$。 
5. 到达车站后$v$，我们立即添加它的奖金$a_v$如果$v \neq 1, n$。 这对一次性性质进行了建模，因为我们只保留每个节点的最佳到达状态； 用更差或相同的时间重新审视并不能改善未来的状态。 
6. 如果我们在任何时候到达车站$n$，我们返回 true。 
7.二分查找最小$X$这样`can(X)`是真的。 

为什么它有效：该算法保持了以下不变式：`best[i]`是到达车站后可实现的最大剩余时间$i$通过当前初始预算下的任何有效的访问节点序列。 任何在节点的剩余时间上不是严格更好的路径都无法在未来的转换中提供帮助，因为所有边缘成本都是非负的，并且每个节点条目的奖金是固定的。 这保证了修剪主导状态保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n, d = map(int, input().split())
    a = [0] * n
    if n > 2:
        vals = list(map(int, input().split()))
        for i in range(1, n - 1):
            a[i] = vals[i - 1]

    pts = [tuple(map(int, input().split())) for _ in range(n)]

    dist = [[0] * n for _ in range(n)]
    for i in range(n):
        x1, y1 = pts[i]
        for j in range(n):
            x2, y2 = pts[j]
            dist[i][j] = (abs(x1 - x2) + abs(y1 - y2)) * d

    def can(X):
        best = [-1] * n
        pq = [(-X, 0)]
        best[0] = X

        while pq:
            neg_t, u = heapq.heappop(pq)
            t = -neg_t

            if t < best[u]:
                continue

            if u == n - 1:
                return True

            for v in range(n):
                if v == u:
                    continue
                cost = dist[u][v]
                if t < cost:
                    continue

                nt = t - cost
                if 0 <= v < n and v != 0 and v != n - 1:
                    nt += a[v]

                if nt > best[v]:
                    best[v] = nt
                    heapq.heappush(pq, (-nt, v))

        return False

    lo, hi = 0, 10**7
    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```核心实现围绕`can(X)`，它模拟固定起始预算下的最佳可能运动。 优先级队列确保我们始终首先扩展最有希望的状态。 这`best`数组通过丢弃主导状态来防止指数爆炸。 二分查找包含了这个可行性检查。 

一个微妙的细节是，车站奖金适用于到达时而不是出发时。 另一个是，我们永远不允许重新访问节点，除非我们以严格更多的剩余时间到达，这可以正确地模拟一次性站点的使用情况，而无需显式跟踪访问集。

 ## 边缘情况

 一个关键的边缘情况是，除非被迫，否则最佳路线永远不会访问高奖金站点。 该算法处理这个问题是因为状态只有在改善剩余时间时才会传播，因此自然避免了不必要的弯路。 

另一种情况是，当一个电台提供足够的奖金以使以前不可能的长边变得可行时。 由于我们在到达时立即添加奖励，因此 Dijkstra 状态在探索传出边缘之前正确反映了扩展的功能。 

最后，当多条路径以不同的剩余时间到达同一节点时，只有最好的路径能够生存下来`best`，确保次优到达不会破坏搜索空间，同时仍然保留所有潜在的最佳未来扩展。
