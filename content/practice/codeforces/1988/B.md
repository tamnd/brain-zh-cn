 ## 解决方案
 ## 问题理解

 我们得到一个可以随时间改变形状的二进制序列。 唯一允许的移动是采用任何连续的段并将其压缩为等于该段的大部分的单个值，其中关系被解析为零。 每个操作都会减少序列的长度，因此最终我们得到一个数字。 

任务是确定是否可以将整个序列简化为等于 1 的单个元素。 

关键的困难在于该操作是不可逆的，并且它会改变长度和值的分布。 如果使用不当，局部看起来有利的片段仍然可能会破坏全局结构。 这个决定纯粹是关于存在，而不是建设。 

约束允许跨测试用例最多有 2·10^5 个元素。 任何模拟操作或尝试搜索段的解决方案都会太慢，因为每个操作本身都是 O(n)，并且在收敛之前可能有很多操作。 即使每个测试用例都采用二次方法也会太大。 

一些微妙的边缘情况值得指出。 

单个零，例如输入`0`，显然不可能变成`1`因为没办法介绍。 

像这样的字符串`10`也是不可能的：唯一的段操作要么是单例，要么是整个数组。 整个数组有一个零和一个一，所以大多数都是零，这会将所有内容折叠为`0`。 

一个更有趣的案例是这样的`10001`。 即使存在，它们也是稀疏的，任何包含太多零的操作都会立即翻转为零，从而使恢复变得不可能。 

这些例子表明，答案不是由细分结构决定的，而是由全球平衡条件决定的。 

## 方法

 暴力视图试图模拟所有可能的操作。 在每一步中，我们都可以选择任何子数组，计算其多数，然后递归地继续生成的序列。 这形成了一个巨大的搜索树，其中每个状态分支为 O(n^2) 种可能性，深度也可以是 O(n)。 即使使用记忆，不同状态的数量也是指数级的，因为不同的压缩序列会产生不同的中间数组。 这种方法很快就变得不可行。 

关键的观察结果是该操作具有很强的单调行为：它仅减少数组并用反映局部多数的单个位替换局部结构。 重要的是，只有当它们在某些地区具有足够的主导地位时，它们才会被保留下来。 当存在任何局部平局或零多数时，零作为默认结果。 

我们想以一个结束`1`，这意味着在某个时刻必须存在一个段，其重复压缩永远不会消除所有段。 如果在任何阶段我们创建一个以零为主的段，那么该段就会崩溃为零，并且无法对最终的段做出贡献。 

这导致了一个关键的简化：以单一结束的唯一方法`1`是如果 1 的总数严格大于零。 如果零等于或更多，则任何全数组操作都会立即崩溃为零，并且之后没有机制可以“恢复”1，因为该过程仅压缩，从不创建 1。 

如果严格来说更多，我们总能找到一系列压缩，逐渐删除零，同时保留大部分 1。 直观上，我们总是可以选择避免翻转全局主导地位的段，最终将数组折叠成一个。 

因此，答案简化为检查 count(1) > count(0) 是否。

 ## 算法演练

 1. 计算输入字符串中 1 和 0 的数量。 这给出了数组的全局摘要，而不需要模拟任何操作。 
2. 比较计数。 如果 1 的数量严格大于 0 的数量，则输出 YES。 否则输出NO。 

### 为什么它有效

 每个操作都会用其多数替换一个段，这永远不会增加段的数量，除非段已经在本地占主导地位。 任何具有至少与 1 一样多的 0 的段都会崩溃为 0，从而永久减少系统中 1 的存在。 如果全局的零不严格少于一，则任何合并整个数组的尝试最终都会产生零，并且由于操作只会减少结构，因此无法重新引入丢失的零。 相反，如果个数严格更多，我们总是可以通过合并精心选择的段来避免将整个结构折叠为零，保留以一为主的配置，直到数组缩小为单个元素。 

这使得计数之间的全球不平等变得必要且充分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    
    ones = s.count('1')
    zeros = n - ones
    
    if ones > zeros:
        print("YES")
    else:
        print("NO")
```该解决方案独立读取每个测试用例并在线性时间内计算计数。 核心逻辑是 1 和 0 之间的比较。 不需要模拟或结构跟踪。 

唯一的微妙之处是确保正确地剥离字符串，因为否则尾随换行符会影响计数。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()
        ones = s.count('1')
        zeros = n - ones
        out.append("YES" if ones > zeros else "NO")
    return "\n".join(out)

 ## 边缘情况

 单元素数组突出显示基本行为。 用于输入`1`，答案是肯定的，因为数组已经等于`[1]`。 该算法正确计算出 1 = 1、0 = 0，并返回 YES。 

用于输入`0`，ones = 0，zeros = 1，因此输出为 NO。 这与通过任何操作引入的不可能相匹配。 

平衡结构如`01`或者`10`总是有相同的计数，导致 NO。 该算法不依赖于排列，这与平衡段的任何完全合并由于平局破坏而崩溃到零的事实是一致的。
