 ## 解决方案
 ## 问题理解

 我们从包含单个数字的多重集开始`n`。 更改此多重集的唯一方法是重复选择一个现有数字`u`，删除它，最多替换为`k`总和恰好为的正整数`u`。 目标是转换多重集，使其最终仅由一个组成，并且我们希望最大限度地减少使用此类替换操作的数量。 

关键的观点是停止从集合的角度思考，而是跟踪单个数量：多重集合中元素的总数。 每一次操作都会用几个较小的数字替换一个数字，从而增加元素的数量，同时保留总和。 由于最终状态必须是`n`，最终的元素数量正好是`n`，总和也是`n`。 

约束足够小，直接贪婪或模拟方法就可以了。 每次操作最多将一个值减少为`k`部分，因此增长过程本质上是对数的。 和`n ≤ 1000`，甚至模拟操作或计算每个测试用例的公式也很容易足够快。 

出现微妙的边缘情况时`n = 1`。 在这种情况下，多重集已经只包含一个，因此不需要任何操作。 另一个边缘情况是当`k`足够大，我们可以一步将任何数字分解为所有数字，但仍然必须遵守至多规则`k`部分。 一个天真的假设，我们总是准确地分成`k`零件将失效时`u < k`。 

## 方法

 蛮力的观点是模拟这个过程：重复选择最大的元素，将其分成一定数量的部分，并继续直到一切都合而为一。 这是正确的，但很混乱，因为不同的分裂选择会导致不同的中间状态。 分支因子很大，因为每个数字可以通过多种方式分为最多`k`部分。 即使对于小`n`，这会创建指数数量的可能序列。 

关键的观察结果是操作顺序并不重要； 重要的是在一个值变成 1 之前我们被迫“扩展”多少次。每次操作都会替换一个数字`u`至多`k`部分，因此最好的策略始终是尽可能均匀地分成精确的部分`k`每当零件`u > 1`。 这可以最大限度地提高进步。 

所以这个过程变得确定性：我们重复替换一个数字`u`和`k`大致相等，直到全部为 1。所需的操作数就是我们需要中断的次数`n`向下直到所有块都为1，相当于重复用最多替换一个节点`k`孩子们在树上，直到我们到达大小为 1 的叶子。 

这简化为一个简单的增长模型：每次操作都会增加件数，我们需要从 1 件增长到`n`件数，每次操作最多增加件数`k - 1`。

 ## 算法演练

 关键思想是跟踪我们当前拥有多少块以及需要多少次操作才能达到至少`n`从一个值开始的。 

1. 我们从一个价值要素开始`n`。 我们从概念上将其视为一个活跃的“块”。 
2. 每个操作占用一个chunk，最多替换为`k`更小的块。 如果我们总是以最佳方式分割，我们会将其视为用精确的替换一个块`k`尽可能分块。 这最大化了每次操作获得的块的数量。 
3. 最初我们有`1`块。 每次操作后，块的数量最多增加`k - 1`，因为删除了一个块并且最多`k`被添加。 
4.我们想要准确地达到`n`块，因为每个最终块对应一个`1`。 
5. 所以我们计算从`1`到`n`使用增量`k - 1`。 这是一个简单的算术增长过程。 
6. 如果`k = 1`，除非`n = 1`。 所以我们分开处理。 

### 为什么它有效

 不变的是，每次操作后，总和保持不变，而当我们分裂成时，碎片的数量增加了最大可能的数量`k`部分。 由于每个最终配置都只是`n`达到目标就等于达到目标`n`件。 与最大分裂的任何偏差只会延迟进度，因此最佳策略始终是最大化每次操作的新片段数量。 这将问题简化为每步增益固定的确定性增长过程。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())

        if n == 1:
            print(0)
            continue

        if k == 1:
            # cannot split anything larger than 1
            print(-1)
            continue

        # each operation increases number of pieces by at most (k-1)
        # start with 1 piece, need to reach n pieces
        need = n - 1
        step_gain = k - 1

        ans = (need + step_gain - 1) // step_gain
        print(ans)

if __name__ == "__main__":
    solve()
```## 工作示例

 ## 边缘情况

 当`n = 1`，多重集已经满足目标，因为它已经只包含多重集，所以不需要任何操作。 该算法正确地立即返回 0。 

什么时候`k = 1`和`n > 1`，任何元素都不能被分割成多个部分，因此我们永远不能增加元素的数量。 因为我们从一个元素开始并且需要`n > 1`，答案是不可能，算法返回`-1`。 

什么时候`k >= n`，一次分割最多可以产生`n`一次操作中，但前提是最多规则允许`k`部分。 如果可能，该公式自然会减少到 1 次操作，从而匹配最佳行为。
