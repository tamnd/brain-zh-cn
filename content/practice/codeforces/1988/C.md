 ## 解决方案
 ## 问题理解

 我们得到一个数字$n$，我们想要构建最长的可能严格递增的正整数序列，其中每个元素最多$n$。 关键约束是每个相邻对必须在按位 OR 下精确组合$n$。 换句话说，如果我们取两个连续的元素$a_{i-1}$和$a_i$，设置的每一位$n$必须已经出现在至少其中一个中，并且除此之外没有多余的位$n$是允许的。 

所以每个元素本质上都是一个“部分掩码”$n$，并通过序列移动意味着逐渐打开更多位，直到我们到达$n$本身。 该序列必须严格递增，因此每一步都必须添加至少一个之前不存在的新位。 

输入大小的值很大，最多$10^{18}$，这立即表明我们应该从位结构而不是数字迭代的角度来思考。 迭代所有数字的任何解决方案$n$是不可能的。 该结构纯粹是关于位的子集$n$，因此复杂度由位数决定，最多 60。 

出现微妙的边缘情况时$n$是二的幂。 在这种情况下，只有一个设置位，并且任何小于$n$不能与其他任何东西结合产生$n$在不违反递增条件的情况下，以有意义的方式进行 OR 操作。 该序列折叠为长度一。 尝试“拆分”位的简单方法会错误地尝试生成无法满足 OR 约束的中间值。 

另一个边缘情况是当$n$有许多设置位，例如$2^k - 1$。 在这种情况下，有许多有效子集，但并非所有子集都可以任意排列成严格递增的 OR 链，该链将最终的 OR 保留为$n$。 正确的构造必须尊重位掩码的包含结构。 

## 方法

 暴力方法会尝试生成从 1 到$n$，过滤那些属于$n$，然后尝试所有满足连续元素之间的 OR 约束的递增子序列。 这很快就变得不可行，因为即使迭代所有数字直到$n$是$O(n)$， 和$n$可以是$10^{18}$。 即使限制为有效子集也无济于事，因为位子集的数量$n$是$2^{\text{popcount}(n)}$，在最坏的情况下是$2^{60}$。 

关键的观察结果是 OR 条件强制采用非常严格的结构：每个步骤必须添加至少一个先前未设置的位$n$，并且一旦在值中设置了某个位，就无法将其删除。 这意味着每个有效序列对应于设置位的顺序$n$，我们逐渐一点一点地打开位。 但是，我们可以重复使用组合，因此我们可以构造逐渐累积位的中间状态。 

最大化长度的一种干净方法是考虑构造所有类似前缀的位掩码$n$，但是如果我们允许不同的激活顺序，我们可以做得比仅仅使用前缀更好。 最佳策略是生成通过按固定顺序获取位子集而形成的所有掩码，但确保每个下一个掩码仅相差一个新激活的位。 这导致序列的长度为$\text{popcount}(n)$，但我们可以通过交错通过删除较高位创建的中间状态来进一步扩展它，同时保持 OR 一致性。 

关键的改进是观察我们可以遍历$n$从最低有效位到最高有效位，对于每一位，我们可以通过以受控贪婪方式插入“激活前”和“激活后”状态来使序列长度效应加倍。 这相当于生成以下形式的所有数字：$$x \mid (n \text{ with higher bits fixed and lower bits varying})$$但尊重递增的秩序。 

这减少了以二进制表示的升序构建所有有效掩码，仅限于子集$n$，它对应于以仔细控制的贪婪递增序列枚举子掩码。 

最优结构是：从 0 开始，贪婪地选择比前一个更大的最小数字，该数字是$n$。 这是有效的，因为 OR 条件确保任何选定的数字都不能引入外部位$n$，并且严格增加确保我们永远不会重新访问某个状态。 贪婪跳转结构自然地最大化了我们可以访问的不同子掩码的数量。

 ## 算法演练

 1.从完整号码开始$n$并认识到每个有效元素必须是子掩码$n$，这意味着它不能包含存在于中的位之外的位$n$。 此限制定义了整个搜索空间。 
2. 构造所有子掩码$n$按递增顺序。 这种排序很重要，因为它自然地强制执行严格递增条件，而无需额外检查。 
3. 迭代这些子掩码并贪婪地选择一个序列：始终采用严格大于先前选择的值的最小子掩码。 这确保了我们在不违反单调性的情况下最大化可以采取的步骤数。 
4. 将每个选定的子掩码附加到答案序列中。 每个新元素与前一个元素至少有一位不同，这保证了严格增加。 
5. 当不存在更大的子掩码时停止。 最后一个元素始终是$n$， 自从$n$它本身是它自己的子掩码，也是最大可能的有效值。 

### 为什么它有效

 核心不变量是，在每一步中，我们都维护最小的可达子掩码$n$大于之前的值。 因为每个有效数字都必须是子掩码，所以跳过任何候选子掩码只能减少序列的长度，而不会增加序列的长度。 贪婪的选择是安全的，因为任何未来的有效延续仅取决于剩余的未使用的较高子掩码，并且选择大于必要的跳转只能消除中间有效状态。 因此，子掩码的贪婪遍历产生与 OR 约束一致的最长严格递增链。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def generate_submasks(n):
    # generate all submasks in increasing order
    submasks = []
    m = n
    while True:
        submasks.append(m)
        if m == 0:
            break
        m = (m - 1) & n
    return submasks

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input().strip())
        
        # generate all submasks
        subs = generate_submasks(n)
        
        # reverse gives increasing order
        subs.sort()
        
        # greedy take all (already strictly increasing)
        print(len(subs))
        print(*subs)

if __name__ == "__main__":
    solve()
```该实现依赖于标准子掩码枚举技巧：重复应用$(m-1) \& n$遍历所有子掩码$n$按降序排列。 然后我们对它们进行排序以获得递增顺序，这直接给出了一个有效的序列。 

关键的微妙之处在于，这是有效的，因为 OR 条件不会强加非相邻元素之间的依赖关系，仅强加位空间中的成员资格$n$。 一旦我们限制子掩码，任何增加的顺序都是有效的。

 ## 边缘情况

 当$n$是2的幂，子掩码集合仅包含两个元素：0和$n$。 过滤为正整数后，序列简化为$n$。 该算法自然只产生该值，因为没有其他子掩码可以在不引入禁止位的情况下表示正有效中间状态。 

什么时候$n$已设置所有位，子掩码数量为最大。 该算法枚举了所有$2^k$位的子集，产生一条长链。 每个转换仍然有效，因为每个数字仍然是$n$，因此 OR 条件自动满足。 

什么时候$n$是稀疏的，例如$2^k + 1$，子掩模结构变得不均匀，但枚举仍然产生正确的递增序列。 该算法不依赖于密度，仅依赖于按位与下的子集闭合$n$。
