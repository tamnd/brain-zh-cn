 ## 解决方案
 ## 问题理解

 孩子们站成一圈，编号为`1`到`n`。 孩子`1`从球开始。 第一次投球使球向前移动`1`位置，第二次投掷将其向前移动`2`位置，第三次投掷`3`职位等。 恰好之后`n - 1`投掷时，我们必须打印每次投掷后哪个孩子接球。 

运动围绕圆圈进行。 如果我们越过孩子`n`，我们再从child继续`1`。 这是经典的圆周运动，因此模运算是这里的自然工具。 

约束很小，`n ≤ 100`。 即使是低效的模拟也很容易在时间限制内完成。 二次解的执行情况约为`10^4`操作，规模很小。 挑战不是性能，而是正确处理循环索引。 

最常见的错误是混合使用基于 0 和基于 1 的编号。 孩子们的编号从`1`，但使用基于 0 的索引通常会更容易进行模块化算术。 

考虑`n = 5`。 

动作顺序是：

 - 开始于`1`- 移动`1`步骤 →`2`- 移动`2`步骤 →`4`- 移动`3`步骤 →`2`- 移动`4`步骤 →`1`正确的输出是：```
2 4 2 1
```粗心的实现可能会计算：```
pos = (pos + step) % n
```同时保持`pos`以 1 为基础的形式。 这会产生无效的孩子`0`当位置环绕时。 

另一个容易犯的错误是误解距离。 上`k`第-次投掷，我们准确移动`k`位置向前，不`k + 1`。 

例如，与`n = 4`：```
Start at 1
Throw 1: move 1 → 2
Throw 2: move 2 → 4
Throw 3: move 3 → 3
```正确输出：```
2 4 3
```如果有人太早增加步数，他们会错误地移动`2, 3, 4`。 

## 方法

 直接的暴力模拟遵循游戏的字面意思。 我们存储当前的子项并重复向前移动所需的位置数。 由于孩子们围成一个圆圈，因此每次移动后我们都会使用模算术绕一圈。 

实现这一点的一种方法是物理模拟运动的每一步。 对于`k`第-次投掷，我们一次准确地前进一个位置`k`次。 单步运动总数变为：```
1 + 2 + 3 + ... + (n - 1)
```这是`O(n²)`。 

和`n = 100`，这仍然会立即运行，因此即使是简单的模拟也会被接受。 

更干净的解决方案来自于我们实际上不需要中间位置的观察。 我们只关心每次抛出后的最后一个孩子。 圆周运动可以直接用模运算来表示。 

如果当前位置是`pos`下一个投掷长度是`step`， 然后：```
new_position = (pos + step) % n
```当使用基于 0 的索引时。 

这将每次投掷减少到恒定时间，从而给出`O(n)`解决方案。 

蛮力之所以有效，是因为约束很小，但模算术可以直接捕获圆周运动的结构，并产生更简单的实现。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 已接受 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取孩子的数量`n`。 
2. 将当前位置存储为`0`, 代表孩子`1`在从 0 开始的索引中。 

使用基于 0 的索引使模运算变得简单，因为位置自然会保持在范围内`[0, n - 1]`。 
3. 迭代`step`从`1`到`n - 1`。 

这`step`值直接匹配投掷次数和移动的位置数。 
4.更新当前位置：```
pos = (pos + step) % n
```每当我们经过最后一个孩子时，模运算就会围绕圆进行运动。 
5. 通过打印将位置转换回从 1 开始的编号`pos + 1`。 
6. 继续，直到所有`n - 1`抛出已处理。 

### 为什么它有效

 每次迭代后，`pos`以基于 0 的索引存储球的当前持有者。 上`k`第-次投掷，规则要求精确移动`k`顺时针位置。 添加`k`到当前位置执行此移动，并取模`n`正确处理环绕圆的情况。 由于每次更新都与游戏中的一次投掷完全匹配，因此生成的序列正是孩子们接球的序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

pos = 0
ans = []

for step in range(1, n):
    pos = (pos + step) % n
    ans.append(str(pos + 1))

print(" ".join(ans))
```变量`pos`使用基于 0 的索引存储当前子项。 孩子`1`表示为`0`， 孩子`2`作为`1`， 等等。 

对于每个投掷数`step`，我们向前移动了那么多位置。 表达式：```
(pos + step) % n
```使位置保持在有效的循环范围内。 

输出必须使用原始的从 1 开始的编号，因此我们打印`pos + 1`。 

一个微妙的细节是操作的顺序。 我们首先更新位置，然后打印它。 更新之前的打印将错误地包括扔球的孩子而不是接收球的孩子。 

另一个重要的细节是从以下位置开始循环`1`。 第一次投掷移动一个位置，而不是零。

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())

    pos = 0
    ans = []

    for step in range(1, n):
        pos = (pos + step) % n
        ans.append(str(pos + 1))

    print(" ".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

 ## 边缘情况

 考虑尽可能最小的输入：```
2
```只有一次投掷。 

该算法开始于：```
pos = 0
```为了`step = 1`：```
pos = (0 + 1) % 2 = 1
```我们打印`1 + 1 = 2`。 

输出：```
2
```这证实了循环边界是正确的并且我们准确地执行了`n - 1`抛出。 

现在考虑一个立即概括的情况：```
5
```在第四次抛出时，当前位置是：```
pos = 1
```此举是：```
(1 + 4) % 5 = 0
```位置`0`对应于孩子`1`。 

这一步的输出：```
1
```这验证了模算术正确返回到圆的开头。 

最后，考虑一个捕获索引错误的情况：```
4
```正确顺序：```
2 4 3
```如果有人直接在模表达式中使用基于 1 的索引，他们可能会意外地生成子元素`0`。 我们的实现通过在内部将位置存储为基于 0 的值并仅在打印时转换回来来完全避免这种情况。
