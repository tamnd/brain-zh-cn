 ## 解决方案
 ## 问题理解

 表的每一行都包含整数，并且我们必须从每一行中采用正长度前缀。 如果我们选择`c[i]`行中的单元格`i`，那么该行中选定的单元格恰好是第一个`c[i]`条目。 

总奖励是所有选定号码的总和。 该限制来自前缀长度的序列：$$c_1 > c_2 < c_3 > c_4 < \dots$$不等式在相邻行之间交替。 奇数索引行的行为类似于峰，偶数索引行的行为类似于谷。 

任务是在尊重这种交替条件的同时最大化总和。 

工作台尺寸可达`1500 x 1500`。 这个值足够大，以至于任何独立涉及所有行配置对的算法都会陷入困境。 行可以选择任意前缀长度`1`到`m`，所以一个朴素的状态空间已经有`m^n`可能性，这是完全不可能的。 

即使是对相邻行的动态编程也需要小心。 从每个先前的前缀长度到每个当前的前缀长度的直接转换成本`O(m^2)`每行。 和`n,m ≤ 1500`，就变成：$$1500 \times 1500^2 \approx 3.4 \times 10^9$$操作，远远超出极限。 

这些约束强烈表明我们需要一个将转换优化为每行线性时间的 DP。 

一些边缘情况很容易被错误处理。 

考虑每个值都是负数的情况：```
2 3
-5 -2 -1
-7 -3 -4
```我们仍然必须从每一行中至少选择一个单元格。 允许空前缀的粗心实现将错误地返回`0`。 

另一个危险的情况是最佳过渡不唯一：```
3 3
5 -100 5
1 1 1
5 -100 5
```最佳选择并不总是最长的有利可图的前缀。 独立最大化每一行的贪婪策略会失败，因为交替的不等式会耦合相邻的行。 

边界不等式也很重要：```
2 2
10 10
1 1
```第一行不能选择长度`1`如果第二行也选择`1`，因为该模式需要`c1 > c2`。 相同长度无效。 

最后，平等很重要。 该关系每行都会改变方向。 行之间的转换有效`1`和`2`行之间无效`2`和`3`。 忘记这一点会产生默默的错误答案。 

## 方法

 蛮力的想法很简单。 对于每一行，尝试每个可能的前缀长度`1`到`m`。 检查结果序列是否满足交替不等式，然后计算总前缀和。 

这是可行的，因为每行中的选择完全由单个整数（前缀长度）决定。 问题在于可能性的数量：$$m^n$$和`m = 1500`和`n = 1500`，这是没有希望的。 

下一个自然改进是动态编程。 

首先计算每行的前缀和：$$pref[i][j] = \text{sum of first } j \text{ numbers in row } i$$然后定义：$$dp[i][j]$$作为处理行后可获得的最大总和`1..i`，其中行`i`选择前缀长度`j`。 

转变取决于不等式的方向。 

如果行`i-1`必须大于行`i`， 然后：$$dp[i][j] = pref[i][j] + \max(dp[i-1][k]), \quad k > j$$如果行`i-1`必须小于行`i`， 然后：$$dp[i][j] = pref[i][j] + \max(dp[i-1][k]), \quad k < j$$这个 DP 是正确的，但是幼稚的实现会检查所有`k`对于每一个`j`，导致`O(nm^2)`。 

关键的观察结果是，每个转换仅要求前一行的范围最大值。 对于固定行，我们反复需要：```
maximum over k < j
```或者```
maximum over k > j
```这些可以在线性时间内用前缀最大值或后缀最大值来维护。 

假设我们正在处理一行，其中我们需要比当前长度小的先前长度。 建造：$$best[j] = \max(dp[i-1][1..j])$$然后：$$\max_{k<j} dp[i-1][k] = best[j-1]$$类似地，当我们需要先前的长度大于当前的长度时，构建后缀最大值。 

这减少了每一行`O(m^2)`到`O(m)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(m^n) | O(m^n) | O(n) | 太慢了 |
 | 天真的DP | O(nm²) | O(米) | 太慢了 |
 | 最佳| O(纳米) | O(米) | 已接受 |

 ## 算法演练

 1. 计算每行的前缀和。 

让`pref[i][j]`是第一个的总和`j`行中的单元格`i`。 这允许恒定时间访问通过选择前缀长度贡献的值。 
2. 初始化第一个 DP 行。 

对于行`1`，每个前缀长度都是有效的，因为没有前一行。$$dp[j] = pref[1][j]$$3. 逐行处理。 

对于每个新行，转换取决于当前行是否应大于或小于前一行。 
4. 如果所需的关系是`previous > current`，构建后缀最大值。 

定义：$$suf[j] = \max(dp[j], dp[j+1], \dots, dp[m])$$然后对于当前长度`j`，最佳有效的先前状态是：$$suf[j+1]$$因为我们需要严格更大的先前长度。 
5. 如果需要的关系是`previous < current`，构建前缀最大值。 

定义：$$pre[j] = \max(dp[1], dp[2], \dots, dp[j])$$然后对于当前长度`j`，最佳有效的先前状态是：$$pre[j-1]$$6. 添加当前行贡献。 

一旦知道了最佳有效的先前状态，就可以计算：$$ndp[j] = best + pref[i][j]$$7. 将旧的 DP 阵列更换为新的。 

处理完当前行的所有长度后，继续处理下一行。 
8. 答案是最终 DP 数组中的最大值。 

### 为什么它有效

 DP 状态完全捕获未来决策所需的所有内容：当前行索引和该行中所选的前缀长度。 

任何有效的延续仅取决于下一行的前缀长度是否必须更大或更小。 一旦当前长度固定，前面的行就不再重要。 

优化的转换保持正确，因为前缀和后缀最大值准确地表示在先前长度的允许范围内可实现的最佳 DP 值。 不会跳过任何有效的转换，也不包含无效的转换，因为通过使用强制执行严格的不等式`j-1`或者`j+1`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    n, m = map(int, input().split())

    pref = [[0] * (m + 1) for _ in range(n)]

    for i in range(n):
        row = list(map(int, input().split()))
        for j in range(1, m + 1):
            pref[i][j] = pref[i][j - 1] + row[j - 1]

    dp = [-(INF)] * (m + 1)

    for j in range(1, m + 1):
        dp[j] = pref[0][j]

    for i in range(1, n):
        ndp = [-(INF)] * (m + 1)

        # previous > current
        if i % 2 == 1:
            suf = [-(INF)] * (m + 2)

            for j in range(m, 0, -1):
                suf[j] = max(suf[j + 1], dp[j])

            for j in range(1, m + 1):
                best = suf[j + 1]
                if best > -INF:
                    ndp[j] = best + pref[i][j]

        # previous < current
        else:
            pre = [-(INF)] * (m + 1)

            for j in range(1, m + 1):
                pre[j] = max(pre[j - 1], dp[j])

            for j in range(1, m + 1):
                best = pre[j - 1]
                if best > -INF:
                    ndp[j] = best + pref[i][j]

        dp = ndp

    print(max(dp[1:]))

solve()
```第一部分计算行前缀和。 由于每个选择始终是一个前缀，因此这会将每个行决策转换为恒定时间查找。 

DP 数组仅存储前一行的结果。 满的`n x m`存储是不必要的，因为转换仅取决于紧邻的前一行。 

奇偶校验很微妙。 处理行时`i`在从零开始的索引中：```
row 1 > row 2
row 2 < row 3
row 3 > row 4
```所以奇数行`i`要求`previous > current`，同时甚至`i`要求`previous < current`。 

后缀最大数组处理严格的大于转换。 对于当前长度`j`，先前的有效长度是`j+1 ... m`，所以我们查询`suf[j+1]`。 

前缀最大数组处理严格的小于转换。 对于当前长度`j`，先前的有效长度是`1 ... j-1`，所以我们查询`pre[j-1]`。 

使用非常消极的哨兵可以避免意外地将无法到达的状态视为有效。

 ## 边缘情况

 考虑全否定的情况：```
2 3
-5 -2 -1
-7 -3 -4
```前缀和变为：```
Row 1: -5 -7 -8
Row 2: -7 -10 -14
```DP 决不允许跳过一行，因为状态仅针对长度而存在`1..m`。 最佳有效选择是：```
c1 = 2
c2 = 1
```给予：```
-7 + (-7) = -14
```或者：```
c1 = 3
c2 = 1
```给予：```
-8 + (-7) = -15
```最优答案是`-12`，获得自：```
c1 = 2
c2 = 1
```在正确考虑实际前缀和之后。 允许空前缀的错误实现会错误地输出`0`。 

现在考虑平等：```
2 2
10 10
1 1
```有效对是：```
(2,1)
```仅有的。 

这对`(1,1)`无效，因为第一个关系必须是严格的：$$c_1 > c_2$$后缀最大转换通过查询自动强制执行此操作`suf[j+1]`而不是`suf[j]`。 

最后，考虑奇偶校验：```
3 2
5 5
1 1
10 10
```有效模式是：$$c_1 > c_2 < c_3$$选择：```
(2,1,2)
```是有效的。 

选择：```
(2,1,1)
```失败，因为第三个关系要求第三行大于第二行。 

该算法基于行奇偶校验在后缀和前缀转换之间切换，因此每个不等式方向都得到正确执行。
