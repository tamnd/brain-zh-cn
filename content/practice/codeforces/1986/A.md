 ## 解决方案
 ## 问题理解

 我们在一维数轴（特别是 X 轴）上给出了三个整数点。 任务是找到一个整数坐标，使得从该选定点到三个给定点的距离之和最小。 距离度量是通常的绝对差，因此对于一个点$a$和一个点$x_i$，距离为$|a - x_i|$。 

输入由多个测试用例组成，每个测试用例指定 1 到 10 范围内的三个整数。每个测试用例的输出是一个整数，表示可以实现的最小总距离。 

由于这些点被限制在一个非常小的范围内，一种简单的方法甚至可以检查从 1 到 10 的所有可能的整数坐标。但是，为了理解问题的一般结构，考虑数学属性是有帮助的：对于一条线上的三个点，当所选点是这三个点的中值时，距离之和最小。 这是因为中位数平衡了到左极值和右极值的距离。 

非明显的边缘情况包括两个或所有三个点重合的情况。 例如，如果所有点都为 1，则最佳点也是 1，则总距离为 0。如果两个点为 1，一个点为 10，则最佳选择是 1 或 10，但仔细计算会发现中值方法自然会选择平衡距离的点。 

## 方法

 暴力方法会考虑 1 到 10 之间的每个整数坐标，并计算每个坐标的距离总和。 由于坐标范围极小，这种方法对于这个问题是可行的，尽管从数学角度来看是不必要的。 对于每位候选人$a$，算法求和$|a - x_1| + |a - x_2| + |a - x_3|$。 对于 3 个点和 10 个候选位置，每个测试用例最多需要 30 次距离计算。 鉴于$t \leq 1000$，这只是 30,000 次计算，很容易满足 2 秒的时间限制。 

最佳方法来自于观察绝对差值之和在点的中值处最小化。 将三个点排序，直接取中间值就给出最优坐标$a$。 这将问题简化为简单地对三个数字进行排序，这是常数时间。 无需迭代候选位置或执行重复求和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(t * 10) = O(t) | O(1) | O(1) | 由于输入范围小而被接受 |
 | 基于中值的最优 | O(t) | O(1) | O(1) | 已被接受且最佳 |

 ## 算法演练

 1.读取测试用例数量$t$。 我们将独立处理每个测试用例。 
2. 对于每个测试用例，读取代表 X 轴上的点的三个整数。 
3. 对三个整数进行排序。 这可确保轻松识别最小值、中值和最大值。 
4.选择排序列表的中间值作为最优坐标$a$。 这是中位数，保证距离之和最小。 
5. 计算距离的总和$a$对于三个点中的每一个使用$|a - x_1| + |a - x_2| + |a - x_3|$。 
6. 打印当前测试用例的计算总和。 

为什么有效：对于一条线上的一组三个点，将所选点移离中线会增加至少一个方向上的总距离，而另一个方向上的总距离却不会充分减少。 因此，中位数是使绝对差之和最小化的唯一点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    x = list(map(int, input().split()))
    x.sort()
    median = x[1]
    total_distance = abs(median - x[0]) + abs(median - x[1]) + abs(median - x[2])
    print(total_distance)
```代码首先读取测试用例的数量。 对于每个测试用例，它解析三个坐标，对它们进行排序，并将中间元素作为中位数。 使用绝对值函数，它计算到所有点的距离总和并打印它。 对三个元素进行排序是常数时间，因此这一步在性能方面是微不足道的。 使用中间元素可以保证正确性，而无需检查所有候选坐标。

 ## 边缘情况

 当所有三个点都相同时，例如，`5 5 5`，算法选择中位数`5`。 距离总和为`0 + 0 + 0 = 0`，正确处理这种边缘情况。 

当两点重合且其中一点相距较远时，例如，`1 1 10`, 排序产量`[1, 1, 10]`中位数是`1`。 距离之和为`0 + 0 + 9 = 9`，与选择相比是最小的`10`（将是`9 + 9 + 0 = 18`）。 

当点连续时，例如，`1 2 3`，排序后的列表是`[1, 2, 3]`和中位数`2`产生总和`1 + 0 + 1 = 2`。 选择`1`或者`3`会产生`1 + 1 + 2 = 4`，因此算法正确识别了中位数。 

这证实了基于中值的方法可以正确处理所有小范围边缘情况，而无需特殊情况处理。
