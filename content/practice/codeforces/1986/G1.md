 ## 解决方案
 ## 问题理解

 我们给出了长度的排列$n$，意味着每个数字$1$到$n$只出现一次，但是以某种打乱的顺序出现。 各位置$i$有一个价值$p_i$，我们想要计算索引对$(i, j)$和$i < j$这样这些位置的值的乘积就可以被指数本身的乘积整除。 换句话说，我们想检查什么时候$$i \cdot j \mid p_i \cdot p_j.$$因此，每一对头寸都定义了两种产品：一种来自指数，一种来自价值。 我们计算有多少对指数产品除以价值产品。 

约束条件$n \le 10^5$还有测试总和$10^5$立即排除任何$O(n^2)$每次测试的方法。 甚至$O(n \sqrt{n})$如果常量很大，每次测试都会有风险，因此解决方案必须利用可除结构而不是枚举对。 

当值和索引严重不匹配时，就会出现微妙的边缘情况。 例如，如果$p = [n, n-1, \dots, 1]$，大多数对都是“混合的”，像“相似的指数意味着相似的值”这样的天真的推理就站不住脚了。 另一个棘手的情况是身份排列$p_i = i$，其中每对都满足条件，因为两种产品完全匹配。 粗心的实现可能仍然会尝试对每对进行不必要的检查，从而导致 TLE，即使答案是最大的。 

## 方法

 暴力解决方案检查每一对$(i, j)$并测试是否$i \cdot j$划分$p_i \cdot p_j$。 这是直接且正确的，因为它直接遵循定义。 然而，它执行$\frac{n(n-1)}{2}$每个测试用例的检查，最多可达$5 \cdot 10^9$最坏情况下的输入大小的操作。 这远远超出了可行的限度。 

关键的观察是条件$$i \cdot j \mid p_i \cdot p_j$$可以通过因子分布重新解释。 我们希望每一个主要力量$i \cdot j$出现在$p_i \cdot p_j$。 这以乘法方式将指数和值耦合起来，这表明我们不应该直接考虑头寸对，而应该考虑除数和匹配贡献。 

打破这种条件的标准方法是固定一个索引并将整除条件转换为对第二个索引的约束。 重新排列，$$p_i \cdot p_j \equiv 0 \pmod{i \cdot j}$$相当于要求所有素因数$i$和$j$被覆盖$p_i$和$p_j$。 如果我们将条件重写为：$$\frac{i}{\gcd(i, p_i)} \mid p_j \cdot \frac{p_i}{\gcd(i, p_i)}$$但这看起来仍然很乱。 

关键的简化来自对称性：由于两边都是两项的乘积，因此我们可以为$i$和$j$到任一$p_i$或者$p_j$。 这导致了一个已知的转换：我们不检查乘积的整除性，而是将每个索引值对转换为标准化形式，在其中跟踪哪些除数可以独立满足。 

可行的解决方案是迭代所有可能的值$g = \gcd(i, p_i)$。 对于固定的$g$，我们减少$i$和$p_i$到互质部分：$$i = g \cdot a, \quad p_i = g \cdot b, \quad \gcd(a, b) = 1.$$然后，该条件就成为简化形式对之间的结构化兼容性约束。 这允许通过减少的签名对索引进行分组，并使用频率表而不是显式的对检查来计算有效对。 

因此，问题简化为计算索引对，其简化表示满足整除兼容性条件，这可以使用除数类散列和频率聚合来处理。

 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了 |

 ## 算法演练

 我们根据每个索引值对的最大公约数将其重新表示为简化表示。 这让我们可以对所有对的可分性约束进行本地编码，而不是全局编码。 

### 步骤

 1. 对于每个索引$i$, 计算$g = \gcd(i, p_i)$。 

这就提取了位置和价值之间的共享因素结构，隔离了它们之间的“固定耦合”。 
2. 重写$i$和$p_i$作为：$$a = \frac{i}{g}, \quad b = \frac{p_i}{g}.$$通过建设，$a$和$b$是互质的。 这种分离很重要，因为它可以防止在组合两个指数时重复计算共享因子。 
3. 维护成对的频率图$(a, b)$。 每对代表索引值交互的结构类型。 
4. 处理新位置时$i$，我们想要计算有多少个之前见过的位置$j$与其形成有效的对。 之间的整除条件$(i, p_i)$和$(j, p_j)$减少到之间的兼容性条件$(a_i, b_i)$和$(a_j, b_j)$，可以通过除数匹配来检查$a$-成分。 
5. 对于每个$(a_i, b_i)$, 枚举除数$a_i$。 对于每个除数$d$，计算互补因子并查询频率图以累积有效匹配。 
6. 统计对指数的贡献后$i$， 插入$(a_i, b_i)$进入频率图。 

### 为什么它有效

 变换使用$g = \gcd(i, p_i)$隔离索引和值之间的所有共享质因数，迫使其余部分互质。 这可以防止组合两个索引时出现重叠歧义。 原始的整除条件仅取决于质因数在四个数字中的分布情况$i, j, p_i, p_j$，但标准化后，每个指标贡献独立的因子集。 然后，频率图对兼容的因子分布进行计数，而无需重新组合原始产品，从而确保每个有效对都被精确计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from math import gcd
from collections import defaultdict

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        freq = defaultdict(int)
        ans = 0

        for i in range(1, n + 1):
            x = p[i - 1]
            g = gcd(i, x)
            a = i // g
            b = x // g

            # enumerate divisors of a
            d = 1
            divs = []
            while d * d <= a:
                if a % d == 0:
                    divs.append(d)
                    if d * d != a:
                        divs.append(a // d)
                d += 1

            for d in divs:
                # match with previous states that can complement this divisor
                ans += freq[(d, b)]

            freq[(a, b)] += 1

        print(ans)

if __name__ == "__main__":
    solve()
```实现的核心是使用 gcd 的缩减步骤。 这确保每个索引都提供标准化签名。 除数枚举是按$a = i/g$，这是有效的，因为所有数字的除数之和达到$n$的边界是$O(n \log n)$。 

一个微妙的细节是更新的顺序：我们在插入当前元素之前查询频率图。 这保证了每对都被精确计数一次$i < j$，避免重复计算。

 ## 边缘情况

 最小输入$n=1$不产生对，并且算法正确地返回零，因为循环从不处理对，并且频率图仅在初始化后使用。 

在相反的排列中，例如$p = [n, n-1, \dots, 1]$，gcd值差异很大，导致大多数$(a, b)$签名有所不同。 基于除数的查找确保不会计算错误匹配，因为兼容性需要简化形式的精确结构对齐。 

在身份排列中$p_i = i$， 每一个$g = i$，所以每一个$a = 1$和$b = 1$。 所有索引都合并为一个签名，并且频率累积正确地产生$\binom{n}{2}$，匹配有效对的数量。
