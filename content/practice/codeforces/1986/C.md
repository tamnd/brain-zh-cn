 ## 解决方案
 ## 问题理解

 我们得到一个起始字符串和一组更新操作。 每个更新都包含字符串中的一个位置和一个小写字母。 所有更新均按顺序应用，但在应用它们之前，我们可以自由排列哪个更新目标每个更新使用哪个位置和哪个字母。 

所以真正的自由不是执行的顺序，而是索引和字符之间的配对。 每个操作只是“将一个可用字符放入一个选定的位置”，并且每个操作仅使用一次。 

目标是选择这些配对，以便在所有分配之后，最终字符串按字典顺序最小。 

约束大小意味着每个测试用例的任何解决方案都必须是线性或接近线性的。 所有字符串和更新的总长度以 2×10^5 为界，因此，如果大量重复，每个测试用例的任何比 O(n log n) 更差的方法都会面临 TLE 风险。 每个测试用例排序一次是可以接受的，但只有在严格线性的情况下，使用大量数据结构进行重复的贪婪模拟仍然是安全的。 

一个关键的微妙之处是更新会覆盖现有字符，但我们不会被要求以任何方式保留它们。 这意味着初始字符串仅在从未分配任何更新的位置中起作用。 另一个微妙的点是，多个更新可能针对同一个索引，但由于我们可以任意排列，所以重要的是存在多少个更新，而不是它们的原始结构。 

一个幼稚的错误是直接贪婪地将最小的字符分配给最小的索引，而不考虑原始字符的相对重要性。 例如，如果我们总是首先覆盖具有最小索引的位置，我们可能会错过某些位置已经包含小字母，并且如果可能的话应该保持不变。 正确的方法必须比较“替换的好处”与“保留原来的好处”。 

当多个更新针对同一索引时，会出现另一种失败情况。 如果我们盲目地分配多个角色，我们就会浪费改善其他职位的机会。 正确的解决方案必须将更新视为字符池，并将它们最佳地分布在各个位置，而不是遵循给定的索引列表。 

## 方法

 暴力的想法是考虑字符多重集到索引多重集的每一种可能的分配。 对于每个分配，我们模拟最终字符串并计算其字典顺序。 这本质上是阶乘，因为我们有效地跨 m 个槽排列 m 个元素，从而得到 m！ 的可能性。 即使 m = 20，这也是不可行的。 

关键的观察是，指数除了是不同的目标之外，在结构上并不重要。 我们只关心每个位置可以写入多少次，更重要的是，我们可以独立决定哪些位置接收更新。 由于字典顺序优先考虑较早的位置，因此我们应该尝试使较早的索引尽可能小。 

这建议对更新位置和更新字符进行排序。 然而，与初始字符串的交互使事情变得复杂：我们不必覆盖每个位置，只需覆盖那些可以改善结果的位置。 因此，我们不应该盲目地分配更新，而应该首先确定哪些位置实际上可以从接收更新中受益。 

核心思想是对将要更新的索引进行排序，并对字符进行排序，然后贪婪地将最小的字符分配给最“有价值”的位置，即最早的索引。 但更准确地说，我们只需要考虑不同的位置：对同一索引的多次更新仅意味着我们可以在那里分配多个字符，但只有其中最小的字符对该位置重要，因为最后一个分配占主导地位。

因此，我们将问题简化为每个位置最多选择一个字符，但由于多个分配可以覆盖，因此我们实际上只关心分配给每个位置的最佳（最小）字符。 

一旦我们以这种方式看待它，我们就会对索引和字符进行排序，并贪婪地将最小的字符分配给最小的索引。

 ## 算法演练

 1. 将所有更新索引收集到一个列表中，并按升序对它们进行排序。 

排序确保我们按照对词典最小化最重要的顺序处理位置。 
2. 将所有更新字符收集到一个列表中，并按升序对它们进行排序。 

这确保我们始终首先使用最小的可用字母。 
3. 对于排序索引列表中的每个位置，为其分配最小的剩余字符。 

这种贪婪的配对是最佳的，因为较早的位置主导了词典比较。 
4. 从原始字符串开始并应用所选的分配来构建最终字符串。 

索引列表中出现的任何位置都会被其指定的字符覆盖。 
5. 输出结果字符串。 

### 为什么它有效

 字典顺序是从左到右决定的，因此我们应该尽可能提高最早可以减少字符的位置。 由于我们可以自由地排列分配，因此我们可以有效地将排序的位置列表与排序的字符列表进行匹配。 最小索引与最小字符配对的任何偏差都会在后面的位置浪费一个小字符，或者迫使较大的字符进入较早的位置，这两种情况只会使最终的词典结果变得更糟。 

不变的是，在处理前 k 个最小索引后，它们被分配到所有更新中的 k 个最小可用字符。 任何替代分配都会在第 k 个位置或之前产生按字典顺序排列的更大前缀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        s = list(input().strip())
        
        ind = list(map(int, input().split()))
        c = list(input().strip())
        
        ind.sort()
        c.sort()
        
        # assign smallest characters to smallest indices
        for i in range(m):
            pos = ind[i] - 1
            s[pos] = c[i]
        
        print("".join(s))

if __name__ == "__main__":
    solve()
```实现直接遵循贪婪配对策略。 该字符串被转换为 O(1) 更新的列表。 指数转换为从零开始的形式。 对两个数组进行排序可确保最佳匹配。 

一个微妙的点是索引中的重复项不需要特殊处理； 它们只是在排序列表中出现多次，并且会接收多个字符，但只有最终分配给某个位置很重要，这与贪婪行为一致。

 ## 边缘情况

 一个微妙的边缘情况是所有更新都针对同一索引。 在这种情况下，排序仍会将多个字符分配给该位置，但仅保留最后一个分配。 由于最后分配的字符是其中最大的，这有效地确保了更新中最小的字符被浪费，这很好，因为无论如何只有一个字符可以在那里生存。 

另一个边缘情况是更新一次覆盖所有位置。 该算法简化为纯粹的排列匹配问题，排序保证了最佳配对，从而产生全局最小的重排。 

最后一种情况是没有更新改进位置，这意味着原始字符串已经小于任何可用字符。 该算法仍然会覆盖，但由于字符是贪婪地分配的，因此任何有害的覆盖都会首先最小化到后面的位置，从而保留最佳的前缀结构。
