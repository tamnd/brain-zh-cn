 ## 解决方案
 ## 问题理解

 我们给出了从 1 到$n$，我们被要求计算有多少对索引$(i, j)$满足$i < j$和$p_i \cdot p_j$可除以$i \cdot j$。 从概念上讲，排列表示数字 1 到$n$，所以每个数字只出现一次。 我们没有被要求修改排列，只是为了分析此整除性属性的位置对。 

主要挑战是约束$n \le 5 \cdot 10^5$跨多个测试用例。 使用暴力方法检查所有$\binom{n}{2}$对，操作的数量可以是$10^{11}$在最坏的情况下，这显然是不可行的。 任何迭代所有索引对的解决方案都会超时。 因此，我们需要一种利用问题结构的方法来避免显式检查每个可能的对。 

可能破坏简单实现的边缘情况包括小排列，其中$n = 1$或者$n = 2$，因为粗心的实现可能会尝试访问超出数组边界的索引。 另一个微妙的情况是当排列中的数字大于其位置时，这会影响整除性检查。 例如，如果$p = [2, 1]$，这对$(1, 2)$是有效的，因为$2 \cdot 1 = 2$可以整除$1 \cdot 2 = 2$。 忘记检查整除条件的两边可能会产生错误的答案。 

## 方法

 暴力解决方案只是迭代所有对$(i, j)$和$i < j$并测试是否$p_i \cdot p_j$可以整除$i \cdot j$。 该方法原则上是正确的，但其复杂度为$O(n^2)$。 和$n$最多$5 \cdot 10^5$，这大约产生$10^{11}$最坏情况下的操作，远远超出了3秒时间限制的限制。 因此，我们需要进行优化。 

关键的见解是改变可分性条件$i \cdot j \mid p_i \cdot p_j$进入比率检查：对于固定$i$，条件可以重写为$\frac{p_i}{i} \cdot \frac{p_j}{j}$是一个整数。 如果我们表示$x_i = p_i / i$，则条件变为$x_i \cdot x_j$是整数。 并非所有值$x_i$是整数，但是因为$p_i$和$i$是整数，$x_i$是有理数，并且它的约数是有限的，因为$p_i \le n$。 这导致我们只需要考虑的倍数$i$对于潜在的匹配$j$在哪里$p_j = k \cdot i$对于整数$k$。 通过循环除数或倍数，我们显着减少了候选对的数量。 

我们可以利用这样一个事实：对于每个位置$i$, 有效数量$j$很小，具体受以下倍数的限制$i$那是$\le n$。 这将复杂性降低到$O(n \log n)$对倍数使用类似筛子的迭代。 本质上，不是检查每一个$j > i$，我们只检查那些$j$在哪里$i \mid p_j$和$p_j / i \le n / i$。 这将问题从二次复杂性转变为近线性复杂性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(n)$| 太慢了 |
 | 使用倍数进行优化 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1.初始化一个计数器`ans`到 0。这将存储有效对的数量。 
2. 迭代每个索引$i$从 1 到$n$。 对于每个$i$，识别所有倍数$j = i \cdot k$这样$i < j \le n$。 这些是可分割性可以保留的候选位置。 
3. 对于每一个这样的$j$，检查是否$p_i \cdot p_j$可以整除$i \cdot j$。 这是实际的整除性测试。 我们不能纯粹依赖倍数逻辑，因为$p_i$和$p_j$被排列； 多重启发式减少了候选数，但不保证可分性。 
4. 如果条件成立，则增加`ans`。 
5.全部处理完毕后$i$， 输出`ans`。 

这样做的原因是，通过迭代倍数，我们只考虑候选对$i \cdot j$可以划分$p_i \cdot p_j$。 不变的是所有有效对$(i, j)$满足$i \mid p_j$或者$j \mid p_i$，相当于我们使用的乘法结构。 不会跳过任何有效对，也不计算无效对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        pos = [0] * (n + 1)
        for idx, val in enumerate(p):
            pos[val] = idx + 1  # 1-based index

        ans = 0
        for i in range(1, n + 1):
            j = i
            while j <= n:
                if i < j:
                    if (p[i - 1] * p[j - 1]) % (i * j) == 0:
                        ans += 1
                j += i
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先构造一个基于 1 的位置映射，以便于轻松进行索引乘法。 外循环迭代$i$内循环迭代多个$i$减少候选人$j$价值观。 模检查确保我们只计算有效对。 

一个微妙的点是使用`i < j`在内循环内部； 的一些倍数`i`可能小于`i`如果我们从`i = 1`。 使用从 1 开始的索引可以避免访问时出现差一错误`p`。
