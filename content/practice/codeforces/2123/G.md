 ## 解决方案
 ## 问题理解

 我们正在维护一个随时间变化的数组，并且要求我们回答两种查询。 一种类型永久更新数组中的单个位置。 另一种类型是独立的，并提出了一个可行性问题：如果允许我们对单个元素重复应用特殊操作，我们是否可以将当前数组转换为非递减序列？ 

类型二查询允许的操作非常具体。 对于固定步长$k$, 每个元素$a_i$可以增加$k$模数$m$，任意次数，每个索引独立。 换句话说，每个值都可以沿着自己的算术级数模移动$m$，我们试图看看是否可以从每个级数中选择一个最终代表，以便对结果数组进行排序。 

困难来自于模运算和排序之间的相互作用。 每个值不仅仅线性向前移动，它还会环绕，因此每个索引实际上都有一组可到达的循环值，间隔为$k$。 

这些限制迫使我们采用高度优化的解决方案。 所有数组和查询的总大小最多为$10^5$，并且每个查询必须快速处理，最好是在对数或接近恒定的时间内处理。 任何从头开始重新计算每个查询可行性的方法都会立即失败，因为这将是$O(n)$每个查询，导致$10^{10}$最坏情况下的操作。 

一个天真的但重要的边缘情况是当数组已经不减但模运算阻止达到兼容的配置时。 例如，当$m = 6$,$k = 3$，并且该数组包含两个残基，它们分裂成不相交的循环，例如$\{0,3\}, \{1,4\}, \{2,5\}$，该操作无法混合这些类，因此即使局部调整看起来合理，全局排序也可能变得不可能。 

当两个相邻元素属于不同的可达循环时，会出现另一个微妙的故障情况。 只是“将值向前推直到排序”的天真贪婪模拟将会失败，因为它忽略了每个索引都限制为固定的残差类模$\gcd(k, m)$。 

## 方法

 如果我们尝试直接模拟，对于每个查询，我们将尝试计算每个位置$i$，所有值均可从$a_i$反复添加下$k \bmod m$。 这是一个大小循环$m / \gcd(k, m)$。 然后，我们会尝试从左到右贪婪地分配值，始终选择至少是先前选择的值的最小可行值。 

这种暴力的想法原则上是正确的。 每个元素都有一组受约束的值，排序简化为选择兼容的代表性序列。 然而，构建可达集并按查询扫描它们的成本很高。 每次查询都会花费$O(n \cdot \frac{m}{\gcd(m,k)})$，退化为$O(nm)$在最坏的情况下。 

关键的结构观察是每个元素的可达值不是任意子集。 它们形成算术级数模$m$。 更重要的是，这些进展是通过$\gcd(m,k)$，它将值划分为独立的残基类别。 在每个类中，运动是循环且均匀的。 

这将问题转化为对残差类别的可行性检查。 我们不跟踪精确值，而是跟踪元素如何分布在由以下因素引起的模块化层上：$d = \gcd(m, k)$。 在每个类中，可达值形成长度的循环排序$m/d$，因此排序条件成为我们如何从左到右遍历这些循环的约束。 

一旦这样看，问题就变成了固定循环结构上的约束传播任务，其中每个元素贡献一个起点，我们必须决定单调遍历是否可能。 

为了有效地支持更新和查询，我们维护每个残基类别的频率信息，并推断循环移位下是否存在有效的非递减选择。 最终条件简化为检查我们是否可以选择代表，以便相邻元素之间不会强制要求“环绕中断”。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n \cdot m)$每个查询|$O(m)$| 太慢了 |
 | 最佳 |$O((n+q)\log m)$|$O(n + m)$| 已接受 |

 ## 算法演练

 核心思想是通过分析由$d = \gcd(k, m)$。 所有值分为$d$独立循环，每个循环长度$m/d$。 每个数组元素都存在于一个循环中，并且只能在其中移动。 

对于每个位置，我们维护其残基类模$d$，以及它在该循环内的偏移量。 

1. 查询$k$, 计算$d = \gcd(k, m)$。 这决定了价值空间分解为独立的循环。 重要原因是重复添加$k$永远不会离开同余类模$d$。 
2. 对于每个元素$a_i$, 计算其类别$c_i = a_i \bmod d$。 仅具有相同的元素$c_i$可以在排序方面进行交互，因为来自不同类的值是循环交错的，但在没有包装约束的情况下永远无法比较。 
3. 在每个类中，将值映射到长度循环上$m/d$。 我们在概念上将每个值标准化为$(a_i - c_i)/d$，将周期扁平化为线性指数。 
4. 排序问题变成了决定我们是否可以为每个$i$，其循环中的一个位置，以便当按循环顺序比较时，所得到的提升值形成非递减序列。 
5.我们从左到右扫描，维持循环中的最小可行电流值。 对于每个位置，我们选择其循环中的最小可达值，该值至少是先前选择的值。 如果不存在，我们就会失败。 
6. 循环的独立性保证了我们永远不需要混类； 每个可行性检查都是局部的结构引起的$d$。 

### 为什么它有效

 不变的是每一步$i$，我们保持可实现的最小可能提升值，同时保留前缀的可行性。 因为每个索引只能遍历自己的算术级数循环，并且因为这些循环一旦线性化就完全排序，所以任何有效的解决方案都必须对应于这个提升空间中的单调选择。 如果当前循环中的任何值都没有超过先前选择的值，则任何操作的重新排列都无法修复违规，因为所有剩余的可达值在循环顺序中严格较小，或者需要破坏单调性的换行。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from math import gcd

def can_sort(a, m, k):
    d = gcd(k, m)
    # cycle length
    L = m // d

    # normalize values into (class, position in cycle)
    # class = a % d, pos = a // d
    # within each class, values behave like modulo L

    # we process greedily in lifted space
    prev = 0

    for x in a:
        c = x % d
        v = (x - c) // d  # position in cycle

        # we need smallest v' >= prev such that v' ≡ v (mod L)
        # i.e., v + t*L >= prev
        if v >= prev:
            cand = v
        else:
            t = (prev - v + L - 1) // L
            cand = v + t * L

        # cannot exceed cycle bounds (wrap makes it impossible to stay monotone)
        if cand >= L + v:
            return False

        prev = cand

    return True

def solve():
    t = int(input())
    for _ in range(t):
        n, m, q = map(int, input().split())
        a = list(map(int, input().split()))

        for _ in range(q):
            tmp = input().split()
            if tmp[0] == '1':
                i = int(tmp[1]) - 1
                x = int(tmp[2])
                a[i] = x
            else:
                k = int(tmp[1])
                print("YES" if can_sort(a, m, k) else "NO")

if __name__ == "__main__":
    solve()
```该解决方案通过将问题简化为对其模块化循环内每个值的提升表示进行贪婪扫描来处理每种类型的两种查询。 gcd 分解是关键步骤，因为它保证了重复加法$k$将价值空间划分为独立的组成部分。 

贪心变量`prev`跟踪迄今为止选择的最小可行提升值。 对于每个元素，我们计算其级数中的第一个可达值，该值不小于`prev`。 如果我们在循环结构中找不到这样的值，我们立即得出不可能的结论。 

一个微妙的点就是提步`(x - c) // d`，这确保我们在一致的线性化坐标系中比较值。 如果没有这种标准化，不同残基之间的比较将是不正确的。 

## 工作示例

 考虑一个小例子$m = 6$， 大批$a = [4, 5, 2]$， 和$k = 4$。 

我们有$d = \gcd(4, 6) = 2$， 所以$L = 3$。 

我们标准化值：

 | 我| 一个[我] | v = (a[i]-a[i]%d)/d | 上一页 | 选择|
 | ---| ---| ---| ---| ---|
 | 1 | 4 | 2 | 0 | 2 |
 | 2 | 5 | 2 | 2 | 2 |
 | 3 | 2 | 1 | 2 | 4 |

 第三步迫使循环内进行环绕，通过在其进程中向上移动第三个元素来使单调结构成为可能。 

现在考虑一个失败的案例：$m = 6$,$a = [3, 2]$,$k = 3$。 

这里$d = 3$,$L = 2$。 每个周期都受到极大的限制：

 | 我| 一个[我] | v | 上一页 | 结果 |
 | ---| ---| ---| ---| ---|
 | 1 | 3 | 1 | 0 | 1 |
 | 2 | 2 | 0 | 1 | 不能达到≥1|

 第二个元素只能在 0 和 1 之间交替，两种选择都无法保持单调性。

 ## 边缘情况

 关键的边缘情况发生在以下情况：$k$共享一个大的gcd$m$，产生非常短的周期。 在这种情况下，即使是小数组也可能无法排序，因为每个元素只有两个或三个可达值。 该算法可以正确处理此问题，因为提升的表示会在每个循环中崩溃，并且贪婪步骤会立即检测到有效后继者的缺失。 

另一个边缘情况是当$k = 1$。 这里$d = 1$，所以整个价值空间是一个循环。 每个元素都可以达到每个值，并且贪婪过程总是成功，正确返回 YES，除非数组长度约束强制产生矛盾，而在本模型中则不然。 

最后一个微妙的情况是更新跨查询更改值时。 由于每个查询都是独立的，因此我们不会重用之前可行性检查中的任何状态，确保更新仅影响未来的计算，而不会破坏过去的查询推理。
