 ## 解决方案
 ## 问题理解

 我们有一个锦标赛`n`玩家。 玩家`i`有实力`a[i]`。 如此反复，选出两名幸存的选手，较弱的一名被淘汰。 如果双方实力相当，则任何一方都可能被淘汰。 

该过程恰好在以下时间停止`k`球员留下来。 我们对某个特定的球员感兴趣`j`。 问题是是否存在某种对选择和平局结果的序列，允许玩家`j`仍然活着进入决赛`k`玩家。 

关键词是“有什么办法吗”。 我们不要求概率，也不需要玩家在所有可能的锦标赛结果下生存。 我们只需要一个有利的序列。 

约束足够大，以至于不可能对锦标赛状态进行任何模拟。 在所有测试用例中，玩家总数达到`2 · 10^5`，所以我们应该期望`O(n)`或者`O(n log n)`解决方案。 任何探索锦标赛括号、幸存者子集或状态空间转换的东西都会呈指数增长并立即失败。 

这个问题的一个微妙的方面是，在检查存在性时，配对完全在我们的控制之下。 如果可以通过先选择其他比赛来保护玩家，这是允许的。 

考虑案例```
n = 4, j = 1, k = 1
strengths = [1, 2, 3, 4]
```玩家1是最弱的。 为了成为唯一的幸存者，玩家 1 最终必须击败更强大的玩家，这是不可能的。 正确答案是`NO`。 

现在考虑```
n = 4, j = 1, k = 2
strengths = [1, 2, 3, 4]
```我们可以互相淘汰两个更强的玩家：```
2 vs 3 -> 2 eliminated
4 vs winner -> another player eliminated
```当只剩下两名玩家时，玩家 1 仍然可以活着。 正确答案是`YES`。 

一个常见的错误是认为玩家的相对排名`j`在所有优势中，始终很重要。 只有当我们需要玩家时才重要`j`成为独一无二的冠军。 

## 方法

 暴力方法将对整个锦标赛过程进行建模。 在每个阶段，我们都会选择一对幸存的玩家，执行淘汰，然后递归地继续。 可能的锦标赛状态的数量呈爆炸式增长。 即使对于二十名玩家来说，可能的淘汰序列的数量也是巨大的，这使得这完全不可行。 

蛮力正确的原因是它明确地探索了每一个有效的锦标赛。 它失败的原因是每一步的配对选择数量大致是二次的，从而创建了一个指数搜索树。 

要找到更简单的表征，请关注消除的实际作用。 

每当两名玩家相遇时，一名玩家就会消失。 如果至少有两名玩家比玩家强`j`，我们可以简单地继续匹配那些更强的玩家来对抗。 每场这样的比赛都会淘汰一名强手。 重复这一过程最终只会留下最多一名比他更强的玩家`j`。 

如果比赛停止`k > 1`幸存者，留下一名更强的玩家是完全可以的。 玩家`j`只需要属于幸存者之中，不一定是最强的幸存者。 

唯一困难的情况是`k = 1`。 然后玩家`j`一定是冠军。 冠军在锦标赛中不能有任何严格意义上更强的玩家，因为更强的玩家迟早会击败其他玩家`j`或者击败进入决赛的对手。 

因此：

 如果`k > 1`，每个玩家都可以存活到决赛`k`幸存者。 

如果`k = 1`, 玩家`j`只有当他们的实力等于整个阵法中最大的实力时，才能获胜。 

这将整个问题简化为单个最大检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 | 每个测试用例 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取玩家实力`j`，即`a[j-1]`。 
2.如果`k > 1`，立即回答`"YES"`。 

当允许超过一名幸存者时，我们总是可以安排其他玩家之间的比赛，避免淘汰玩家`j`直到仅`k`球员留下来。 
3.如果`k = 1`，计算数组中的最大强度。 
4. 比较`a[j-1]`与该最大值。 

如果相等，则回答`"YES"`。 

否则回答`"NO"`。 
5. 对所有测试用例重复此操作。 

### 为什么它有效

 当`k > 1`，我们只需要玩家`j`为了生存，而不是成为冠军。 任何时候都有超过`k`剩下的球员，我们可以选择两名不同的球员`j`只要有可能。 其他玩家之间的淘汰减少了场地，同时保留了玩家`j`。 最终只有`k`球员留下来，球员`j`还活着。 

什么时候`k = 1`, 玩家`j`一定是最后的幸存者。 任何实力严格意义上的强者都不会输给玩家`j`，所以这样的玩家会阻止玩家`j`从成为冠军。 相反，如果玩家`j`实力达到最大，剩下的对手都没有更强。 通过适当地安排比赛并在实力相等时利用有利的平局结果，玩家`j`可以成为冠军。 

这两个观察结果完全描述了所有可能情况的特征。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n, j, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        if k > 1:
            print("YES")
        else:
            print("YES" if a[j - 1] == max(a) else "NO")

solve()
```实现直接遵循证明。 

对于每个测试用例，我们首先检查是否`k`超过`1`。 在这种情况下，答案总是`"YES"`，因此不需要进一步的工作。 

只有`k = 1`案例需求分析。 我们检索玩家的实力`j`使用`j - 1`因为 Python 数组是零索引的，而问题使用一索引的玩家编号。 

比较必须是针对全球最大实力，而不是针对更强玩家的数量。 相同的最大值就足够了，因为可以以对玩家有利的方式解决平局`j`。 

该代码执行单遍来计算最大值，为每个测试用例提供线性时间。

 ## 边缘情况

 考虑：```
1
4 1 1
1 2 3 4
```玩家 1 的强度为 1，而最大值为 4。算法输入`k = 1`分支并比较`1`和`4`，生产`NO`。 这是正确的，因为玩家 1 最终必须面对更强的玩家并输掉比赛。 

考虑：```
1
5 1 2
1 2 3 4 5
```该算法看到`k > 1`并立即输出`YES`。 粗心的解决方案可能会拒绝玩家 1，因为他们是最弱的。 这是错误的，因为我们只需要玩家 1 留在最后两名幸存者中，而不是赢得整个锦标赛。 

考虑：```
1
5 3 1
7 7 7 7 7
```最大强度为 7，玩家 3 的强度也为 7。算法输出`YES`。 这可以正确处理关系。 由于同等强度的比赛可能会淘汰任何一位参赛者，因此存在玩家 3 成为最终冠军的序列。 

考虑：```
1
4 2 1
5 5 1 1
```玩家 2 分享最大的力量。 算法输出`YES`因为`a[1] = max(a)`。 即使另一个玩家具有相同的实力，也可以选择平局结果，因此玩家 2 仍然可以是唯一的幸存者。
