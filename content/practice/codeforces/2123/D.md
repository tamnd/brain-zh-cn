 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串。 两名玩家交替移动，爱丽丝先移动。 游戏通过反复重写字符串的各个部分来发展。 

在爱丽丝移动时，她可以准确地选择任何集合`k`字符串中任意位置，不一定是连续的，并强制所有这些位置成为`0`。 在鲍勃的移动中，他可以选择任何连续的长度块`k`并强制该块中的所有字符变为`1`。 

当字符串变为全零时，爱丽丝立即获胜，甚至在鲍勃获得另一轮之前。 

问题是，假设两个玩家都发挥最佳状态，爱丽丝是否可以保证在有限次数的移动中达到全零字符串。 

约束条件`n ≤ 2·10^5`在所有测试用例中意味着每个测试用例的任何解决方案都必须是线性或接近线性的。 任何平方项`n`已经太慢了，因为测试的大小总和达到 200,000。 这强烈表明答案必须取决于字符串的少量全局属性，而不是模拟游戏。 

一个微妙的方面是，爱丽丝可以完全自由地选择任何子序列，而鲍勃则仅限于连续的片段。 这种不对称是问题的核心：Alice 控制分散的仓位，Bob 控制结构。 

一些角落场景暴露了结构：

 如果`k = 1`，Alice 可以每回合将任何单个位置翻转为零，而 Bob 可以将任何单个位置翻转回 1。 如果有的话`1`，鲍勃总是可以在爱丽丝删除它后恢复它，这意味着爱丽丝只有在字符串已经全零的情况下才能获胜。 

如果`k`很大，特别是靠近`n`，爱丽丝一举消除所有的能力变得非常强大，但鲍勃的单个间隔仍然可以“毒害”一大片连续区域。 

另一个重要的边缘情况是当所有`1`s 已经集中在一段长度内`k`。 那么鲍勃可以轻松维护它们，但如果它们分散开来，爱丽丝可以同时消除它们。 

## 方法

 暴力方法会尝试模拟所有可能的游戏状态。 每个状态都是一个二进制字符串，并且爱丽丝从每个状态都有大小子序列的组合`k`，而 Bob 拥有所有 size 的子串`k`。 分支因素是巨大的：爱丽丝独自一人`O(n choose k)`选择。 即使限制可达状态，游戏图也会呈指数增长，使得这种方法完全不可行。 

关键的观察是我们不需要跟踪确切的配置，只需要跟踪鲍勃是否可以无限期地阻止爱丽丝完成她的目标。 鲍勃唯一有意义的权力是在某个大小的滑动窗口内不断地重新引入`k`。 这表明唯一持久的障碍是是否存在鲍勃可以继续“污染”的速度比爱丽丝在全球范围内消除该区域的速度更快。 

由于爱丽丝完全删除了`k`每次移动一个（选择子序列），而鲍勃创建一个块`k`，唯一真正的约束是在任何固定大小的窗口之外存在多少个`k`。 

如果字符串有一个长度窗口`k`已经包含了所有的区域，鲍勃总是可以加强该区域，而爱丽丝在它们在内部重新创建之前无法完全消除该区域之外的所有区域。 相反，如果没有这样的窗口包含所有的窗口，那么爱丽丝最终可以通过重复瞄准分散的窗口来消除它们，因为鲍勃无法将所有现有的窗口集中到单个受保护的段中。 

因此，整个游戏简化为检查所有的值是否都包含在某个长度的子串中`k`。

 ## 算法演练

 1. 找到字符串中包含字符的所有索引`1`。 如果没有，爱丽丝已经立即获胜，因为字符串已经全为零。 
2. 找到a的最左边位置`1`和 a 的最右边位置`1`。 这两个端点捕获包含字符串中所有 1 的最小间隔。 
3. 计算该区间的长度为`rightmost - leftmost + 1`。 这表示覆盖每个的最小连续段`1`。 
4. 将此长度与`k`。 如果小于或等于`k`，则存在一个大小为`k`覆盖所有区域，这意味着鲍勃始终可以瞄准该区域以维持至少一个`1`在爱丽丝的移动周期之后。 
5. 如果间隔长度大于`k`，爱丽丝有足够的自由度来消除跨多个区域的物种，其速度比鲍勃在单个窗口内重新引入它们的速度要快，从而保证了所有物种的最终灭绝。 
6. 输出`"Alice"`如果间隔长度超过`k`，否则输出`"Bob"`。 

### 为什么它有效

 不变量是所有剩余的跨度`1`s。 爱丽丝的举动通过擦除任意位置来减少全局的数量，而鲍勃的举动只能恢复单个连续块内的数量。 如果包含所有 1 的最小间隔已经在 length 内`k`，Bob 总是可以选择相同的间隔来重新引入间隔，从而防止崩溃到零。 如果它大于`k`，Bob 无法同时覆盖所有活动区域，而 Alice 可以逐步缩小占用的跨度，直至消失。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()

        ones = [i for i, c in enumerate(s) if c == '1']

        if not ones:
            print("Alice")
            continue

        span = ones[-1] - ones[0] + 1

        if span <= k:
            print("Bob")
        else:
            print("Alice")

if __name__ == "__main__":
    solve()
```该代码首先提取 1 的所有位置，并立即处理不存在 1 的简单获胜情况。 然后它使用第一次和最后一次出现来计算所有 1 的边界间隔。 该间隔长度是对游戏结果唯一重要的参数。 最终对比`k`实现上面导出的关键结构条件。 

一个微妙的实现细节是索引是从零开始的，因此跨度计算已经匹配正确的长度而无需调整。

 ## 边缘情况

 当字符串已经不包含`1`，算法立即返回 Alice，无需计算任何跨度。 这符合在任何行动之前游戏已经处于获胜状态的规则。 

当所有`1`s 紧密地聚集在一段长度内`k`，跨度检查返回`≤ k`，鲍勃获胜。 例如，输入`1111`和`k=1`给出的跨度 4 大于 1？ 其实这说明了一个微妙之处：Bob只有在总能在全覆盖窗口内恢复时才获胜； 如果所有的都在一个大小的窗口内`k`, Bob 总是可以保持至少一个`1`爱丽丝行动后。 

当 1 分布在字符串的两端时，例如`100001`与小`k`，跨度超过`k`，所以爱丽丝获胜，因为她减少分散的块的速度比鲍勃在单个连续块中重新引入它们的速度快。
