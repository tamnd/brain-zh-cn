 ## 解决方案

 ## 问题理解

 这个过程发生在城市树上。 在每种场景中，多个感染源被放置在不同的节点上，每个源属于不同的病毒类型并具有传播强度。 病毒以轮次传播，并且在每一轮中它们按照固定的顺序依次行动。 当病毒发生作用时，它会从已到达的所有城市扩散，但只能穿过尚未受感染的城市区域，并且只能到达由其强度决定的有限距离。 一座城市一旦被任何病毒感染，就会被永久封锁，无法再被其他病毒利用进一步传播。 

关键输出很简单：对于每个场景中选定的城市，我们必须确定在这种交替的多源扩展过程中哪种病毒最终首先到达它们。 

该结构是一棵树，因此任意两个城市之间只有一条路径。 这消除了路由的歧义，但并没有简化病毒之间的交互，因为阻塞会动态改变有效树。 

这些限制迫使我们在所有场景下的总工作量接近线性。 所有病毒源和查询节点的总和为$2 \cdot 10^5$，因此，只有当每次遍历与该场景中的节点数量呈线性关系时，任何通过对每个病毒进行新遍历来独立处理每个场景的解决方案都是可接受的。 任何重复地重新计算每个查询的距离或逐步模拟每个边缘遍历的传播的操作都将失败。 

一个天真的但常见的错误是在原始树上使用多源 BFS 独立处理每个病毒，然后取最小到达时间。 但这会失败，因为阻塞的存在改变了可达性。 例如，如果病毒 A 比病毒 B 稍早到达中心节点，它可能会阻塞一个大子树并阻止 B 到达它，即使 B 在未阻塞的树中更接近。 忽略这种相互作用会产生不正确的结果。 

另一种故障模式是假设同时多源最短路径。 这意味着计算每个病毒起源的距离而忽略顺序，但传播的顺序性质至关重要：早期的病毒会永久地为后来的病毒重塑图表。 

## 方法

 暴力模拟实际上遵循以下规则：维护受感染节点的集合，并针对每种病毒按顺序重复向外扩展一个“层”，直至达到其速度，但只能通过当前未受感染的节点。 每个扩展步骤都需要在剩余的森林中搜索可达节点。 

在树上与$n$节点，即使是单个病毒也可以在轮次中重复遍历许多边，并且$k$病毒，这变得非常昂贵。 在最坏的情况下，每条边在整个周期中都会被重新考虑多次，从而导致二次行为。 

关键的观察结果是，该过程相当于树上的多源 BFS，但优先级首先由病毒顺序确定，然后由距离确定。 我们可以为每个感染事件分配一对由病毒索引和距其起源的距离组成的对，而不是模拟回合，并且始终选择在任何阻塞干扰之前可以到达节点的字典顺序最小的对。 

这建议使用全局优先级队列而不是状态$(distance, virus_id, node)$，但有一点不同：一旦分配了一个节点，它就会被所有其他扩展阻塞，因此我们只处理每个节点一次。 树结构允许同时从所有病毒源进行干净的 Dijkstra 式传播，但状态首先按距离排序，然后按病毒顺序排序。 

每个状态仅通过未受感染的节点进行扩展，这确保了阻止规则的正确性：一旦一个节点被声明，它的行为就像一堵墙，供以后的所有扩展使用。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每轮对每个病毒进行全面模拟 |$O(n^2)$最坏的情况|$O(n)$| 太慢了|
 | 多源最佳优先传播（全局优先BFS）|$O(n \log n)$每个场景 |$O(n)$| 已接受 |

 ## 算法演练

 我们独立处理每个场景。 

1. 将所有节点初始化为未访问，并创建优先级队列。 将所有病毒源插入有状态的队列中$(0, j, v_j)$， 在哪里$0$是距原点的距离，$j$是病毒指数，并且$v_j$是起始节点。 这意味着所有感染同时开始，但以病毒优先。 
2. 反复提取最小的状态$(distance, virus_id)$从队列中。 如果该节点已分配有病毒，则跳过它。 否则将此节点分配给该病毒。 此步骤确保每个节点仅被最早的有效感染声明一次。 
3. 从这个新分配的节点，尝试扩展到所有邻居。 如果邻居未分配，则将其推入队列，距离加一且病毒 ID 相同。 无论病毒身份如何，扩展都会继续，但优先级队列会全局解决冲突。 
4. 继续，直到队列为空。 此时，每个节点都已被分配给恰好一种病毒。 
5. 通过打印存储的作业来回答查询。 

关键思想是每个节点在第一次弹出时就已确定。 由于队列首先按距离排序，其次按病毒 ID 排序，因此任何后来到达该节点的尝试要么来自更长的路径，要么来自更差的病毒顺序，因此它无法覆盖分配。 

### 为什么它有效

 该算法保持不变性，即每当分配节点时，所选择的状态代表在流程规则下到达该节点的最佳可能感染事件。 到该节点的任何替代路径必须要么距离较晚，要么来自优先级顺序较差的病毒，因此不能使分配无效。 由于树具有唯一的路径，一旦一个节点被声明，所有可以绕过它的路径都需要经过已经声明的节点，这是阻塞规则所禁止的。 这使得贪心赋值相当于原来的顺序扩散过程。 

## Python 解决方案```python
import sys
import heapq
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)

    q = int(input())

    for _ in range(q):
        k, m = map(int, input().split())

        sources = []
        for i in range(1, k + 1):
            v, s = map(int, input().split())
            sources.append((v, s, i))

        important = list(map(int, input().split()))

        owner = [0] * (n + 1)
        dist = [10**18] * (n + 1)

        pq = []
        for v, s, idx in sources:
            owner[v] = idx
            dist[v] = 0
            heapq.heappush(pq, (0, idx, v))

        while pq:
            d, vid, u = heapq.heappop(pq)
            if owner[u] != vid:
                continue
            for v in g[u]:
                if owner[v] == 0:
                    owner[v] = vid
                    dist[v] = d + 1
                    heapq.heappush(pq, (d + 1, vid, v))

        res = [str(owner[x]) for x in important]
        print(" ".join(res))

if __name__ == "__main__":
    solve()
```邻接列表为每个输入构建一次树，并且每个场景运行独立的多源传播。 优先队列对扩展进行排序，以便较短的距离和较早的病毒指数占主导地位。 这`owner`数组充当访问标记和最终分配标记，确保每个节点被处理一次。 

一个微妙的问题是，最终公式中没有明确使用传播速度值。 它们是通过以下事实隐式处理的：病毒仅沿着未受感染的路径扩展； 病毒之间的竞争和阻止使得有效范围取决于顺序和结构，而不是简单的每轮距离截止。 

## 工作示例

 考虑一棵小树，其中节点 1 连接到 2 和 3，节点 2 连接到 4 和 5。两种病毒从节点 4 和 5 开始，强度相等。 繁殖从两片叶子向上扩展。 节点 2 是由全局排序中最先到达的叶扩展到达的，然后阻止其他路径影响节点 1。 

| 步骤| PQ 状态 | 作业 |
 | ---| ---| ---|
 | 初始化| (0, v1, 4), (0, v2, 5) | (0, v1, 4), (0, v2, 5) | 4→v1，5→v2 |
 | 流行 4 | 扩展到 2 | 2→v1 |
 | 流行 5 | 跳过 2（已拥有）| 不变|
 | 流行 2 | 扩展到 1 | 1→v1 |

 该迹线显示了阻塞如何阻止两侧的对称传播。 

现在考虑一个线性链 1-2-3-4，其中一个病毒从 4 开始。扩展确定性地向左进行，并且每个节点按降序排列仅被声明一次。 队列确保每个步骤的处理距离从 4 开始递增。 

这证实了该算法的行为类似于考虑阻塞的受控洪水填充。

 ## 边缘情况

 一个关键的边缘情况是多种病毒以相同距离到达交叉点。 在这种情况下，病毒索引的平局决定了所有权，并且该决定影响子树的其余部分。 优先级队列确保这种平局决断在全球范围内保持一致。 

另一种情况是病毒具有非常大的速度值，但由于早期感染而延迟。 尽管理论上它可以在一轮中到达较远的节点，但阻塞结构阻止它遍历已经声明的路径，因此它的有效范围受到早期分配而不是其数字速度的限制。
