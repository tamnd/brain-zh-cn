 ## 解决方案

 ## 问题理解

 我们得到一排城市，每个城市都有一个从左到右的索引和相关的美丽值。 我们需要选择一系列访问城市，使得指数严格增加。 关键的限制是连续选择的城市不是任意的：位置的增加必须与美丽的增加相匹配。 正式来说，如果我们从城市搬到$i$到城市$j$，那么指数的差异必须等于它们美丽值的差异。 

这个条件可以用更结构化的方式重写。 重新排列$$j - i = b_j - b_i$$给出$$b_j - j = b_i - i$$因此，有效旅程中的所有城市必须具有相同的值$b_i - i$。 这个单一的观察将问题转化为按派生键进行分组。 

目标是选择一组有效的城市（相同的键）并最大化它们的美丽值的总和。 一个组可以由一个城市组成，该组始终有效。 

约束条件$n \le 2 \cdot 10^5$排除任何城市的二次配对。 任何尝试所有对或在所有有效边之间构建转换的解决方案都会降级为$O(n^2)$在最坏的情况下，这太慢了。 我们需要一个线性或近线性的分组策略。 

当所有城市都有不同的特征时，就会出现微妙的边缘情况$b_i - i$价值观。 在这种情况下，每个有效旅程的长度都是一，所以答案就是最大值$b_i$。 假设至少一个有效转换的幼稚方法可能会错误地尝试扩展不存在的链。 

另一个极端情况是许多城市共享相同的信息$b_i - i$但并不连续。 该条件不需要数组中的邻接关系，只需要派生键相等，因此只要保留顺序，跳过索引就是有效的。 

## 方法

 蛮力策略将尝试从每个城市开始并扩展到所有有效的下一个城市。 来自一个城市$i$，我们可以尝试每一个$j > i$并检查转移条件是否成立。 每次成功的转换都会导致递归或 DP 扩展。 这在逻辑上是有效的，因为它直接强制执行约束，但对于每个城市，我们可能会扫描所有后面的城市，从而导致大约$O(n^2)$过渡。 和$2 \cdot 10^5$城市，这是按顺序$4 \cdot 10^{10}$检查，这是不可行的。 

关键的结构简化来自于重写约束。 连续城市的条件仅取决于$b_i - i$。 这意味着整个问题分解为按该值索引的独立组。 一旦分组，不同组之间就没有交互，并且在组内每个关于递增指数的子集都是有效的。 

这将问题变成了一个简单的累积任务：对于每个键$b_i - i$, 求和所有对应的$b_i$值并取所有组中的最大值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（配对检查/DP 过渡）|$O(n^2)$|$O(n)$| 太慢了|
 | 分组依据$b_i - i$|$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 对于每个城市$i$，计算值$key = b_i - i$。 这会将约束转换为分组规则。 这样做的原因是相邻城市之间的原始条件变成了这种表达的平等。 
2. 维护一个从每个键到具有该键的所有城市的美丽值总和的哈希图。 每个城市都为其集团做出独立贡献。 
3. 迭代所有城市，添加$b_i$对应于的总和$b_i - i$。 这构建了每个有效旅程组的总贡献。 
4. 跟踪所有键的最大总和。 这表示选择尽可能最佳的有效旅程，因为任何有效旅程都必须完全位于一个关键组内。 
5. 输出找到的最大值。 

### 为什么它有效

 转变$j - i = b_j - b_i$意味着不变性$b_i - i$跨越所有连续步骤，因此跨越整个序列。 这将城市划分为互不相交的类别，其中的转变始终在内部有效，而在外部则不可能。 任何有效的旅程都是此类中的一个子序列，其整体之美只是其元素的总和。 由于我们可以自由选择类中的任何子集，因此采用该类中的所有元素可以使总和最大化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    b = list(map(int, input().split()))
    
    mp = {}
    ans = 0
    
    for i, val in enumerate(b, start=1):
        key = val - i
        if key in mp:
            mp[key] += val
        else:
            mp[key] = val
        if mp[key] > ans:
            ans = mp[key]
    
    print(ans)

if __name__ == "__main__":
    solve()
```代码直接实现了分组的思想。 枚举从 1 开始，以匹配问题的城市索引。 字典存储每个键的累积和，并且会动态更新答案以避免第二次传递。 

一个常见的陷阱是忘记在关键计算中索引是从 1 开始的。 使用基于 0 的索引会移动所有组并导致不相关城市的错误合并。

 ## 边缘情况

 当$n = 1$，该算法分配一个键并返回该单个值，因为没有任何东西可以组合。 用于输入`[100]`，关键是$100 - 1 = 99$，答案直接是100。 

当所有$b_i - i$值不同，每个组的大小为一。 例如，`[10, 1, 100]`产生钥匙`9, -1, 97`，因此不会发生合并并返回最大单个值。 该算法自然避免了错误的聚合，因为每个键在字典中都是隔离的。 

当所有城市共享相同的密钥时，例如`[1,2,3,4]`，每个城市都贡献一个累加器，并且该算法有效地对整个数组求和。 这表明无需显式构建序列即可完全捕获长有效链。
