 ## 解决方案
 ## 问题理解

 我们得到一个有向图，其中交叉点是节点，道路是单向边。 我们还知道波利卡普实际上从他家开车到工作地点的固定简单路线。 这条路线是有效的，因为每对连续的交叉口都由一条道路连接，但就边数而言，它不一定是最短的可能路线。 

除此之外，还有一个导航系统，不断尝试保持从当前位置到目的地的最短路径。 系统最初选择一些从起点到目的地的最短路径。 每当 Polycarp 遵循下一个推荐的边缘时，系统都会保持其当前计划。 每当他偏离时，系统就会放弃旧的计划，并重新计算从新位置到目的地的最短路径。 

我们需要的数量是这种重新计算（称为重建）可以发生的次数。 由于当存在多条路径时，导航系统可以自由选择任意最短路径，而坡旅甲的路线是固定的，因此答案不是唯一的。 我们必须计算系统做出的所有有效选择的最小可能重建次数和最大可能重建次数。 

约束条件多达二十万个交叉路口和道路，这排除了任何在每一步从头开始重新计算最短路径的解决方案。 在最坏的情况下，每步的新 BFS 将是二次的，并且不会通过。 该结构表明我们应该预处理一次最短距离，然后在恒定时间内评估波利卡普路径的每一步。 

当存在多个最短路径时，就会出现一个微妙的问题。 导航系统在其中的选择决定了波利卡普的下一步是与推荐路线一致还是强制重建。 这意味着答案不仅取决于距离，还取决于从每个节点到目的地的最短路径存在多少个“有效的后续步骤”。 

暴露天真的推理的一个极端情况是每个传出的最短边都通向同一个下一个节点。 在这种情况下，尽管全局上可能存在多条最短路径，但局部系统没有灵活性，波利卡普要么匹配强制边缘，要么根据他的移动触发重建。 

## 方法

 直接模拟将尝试在每一步重建最短路径，然后模拟波利卡普的决策。 这很快就会变得昂贵，因为每次重新计算都涉及图遍历，并且最多可以有 n 个步骤。 最坏的情况是在一个大图上重复运行 BFS，导致三次或接近二次的行为。 

关键的观察是我们永远不需要完整的最短路径结构。 我们只需要知道，对于任何节点 u，哪些邻居可以作为从 u 到目的地 t 的最短路径上的下一个节点。 这可以通过使用反向图上的反向 BFS 计算从每个节点到 t 的最短距离来一次导出。 

一旦我们知道 dist[x]，当 dist[u] = dist[v] + 1 时，有向边 u → v 就是从 u 到 t 的最短路径的一部分。这将导航系统的行为转变为局部规则：在每一步，它只能在满足此等式的传出边中进行选择。 

现在考虑波利卡普从 p[i] 移动到 p[i+1]。 如果这条边与最短距离条件不一致，那么无论系统如何选择，Polycarp 都会强制出现偏差，从而进行重建。 如果一致，则是否发生重建完全取决于系统是否可以选择不同的有效最短边。

对于最少的重建次数，我们假设系统是协作的。 只要 p[i+1] 是有效的最短步邻居，它总是选择 p[i+1]，从而避免不必要的分歧。 仅当 p[i+1] 不是最短步移动时才会发生重建。 

对于最大重建次数，系统会采取对抗性行为。 每当存在与 p[i+1] 不同的替代最短步邻居时，系统就可以选择这样的邻居，迫使 Polycarp 偏离并触发下一步的重建。 仅当 p[i+1] 是唯一有效的最短步邻居时，系统才会被迫遵循它，从而防止重建。 

这将整个问题简化为对于每个步骤计算下一步是否是有效的最短步边缘以及它在这些边缘中是否是唯一的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 重复最短路径的蛮力模拟 | O(k · (n + m)) | O(n + m) | 太慢了|
 | BFS距离+局部最短边检查| O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 反转所有边并从 t 开始运行 BFS 来计算 dist[x]，即每个节点 x 到目的地的最短距离。 这是有效的，因为在反转图中，我们有效地从 t 向后传播最短距离。 
2. 对于每个节点 u，确定有多少个外出邻居 v 满足 dist[u] = dist[v] + 1。该计数表示导航系统在位于 u 时有多少个有效选择。 
3. 将最小和最大重建的两个计数器初始化为零。 
4. 遍历从 p[1] 到 p[k] 的 Polycarp 路径。 对于从 p[i] 到 p[i+1] 的每次转换，检查是否 dist[p[i]] = dist[p[i+1]] + 1。如果这个等式不成立，则该移动不能属于从 p[i] 到 t 的任何最短路径，从而强制重建最小情况。 
5. 对于最大计数，检查p[i]的有效最短步邻居的数量是否大于1或者唯一的有效邻居是否不是p[i+1]。 在任何一种情况下，导航系统都可以选择替代的最短移动，迫使坡旅甲偏离推荐路径并导致重建。 
6. 累积路径中所有边缘的这些条件以获得最终的最小和最大计数。 

正确性取决于最短路径通过距 t 的距离形成分层结构。 每一次最佳移动都会严格地将这个距离减少一倍。 导航系统的自由度正是这个分层图中的分支因素，波利卡普的路径要么遵循这些层之一，要么跳到它外面，迫使重新计算。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

n, m = map(int, input().split())
g_rev = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v = map(int, input().split())
    g_rev[v].append(u)

k = int(input())
p = list(map(int, input().split()))

INF = 10**18
dist = [INF] * (n + 1)

# BFS from destination
t = p[-1]
q = deque([t])
dist[t] = 0

while q:
    u = q.popleft()
    for v in g_rev[u]:
        if dist[v] == INF:
            dist[v] = dist[u] + 1
            q.append(v)

# count valid next steps on shortest paths
good_cnt = [0] * (n + 1)

for u in range(1, n + 1):
    for v in g_rev[u]:
        # reversed graph: v -> u in original, so check original condition via reverse logic
        if dist[v] == dist[u] + 1:
            good_cnt[u] += 1

mn = 0
mx = 0

for i in range(k - 1):
    u = p[i]
    v = p[i + 1]

    on_shortest = (dist[u] == dist[v] + 1)

    if not on_shortest:
        mn += 1
        mx += 1
    else:
        if good_cnt[u] > 1:
            mx += 1

print(mn, mx)
```BFS 在反向图上计算线性时间内从每个节点到目的地的最短距离。 这是唯一需要的全球信息； 其他一切都是通过检查传出的最短路径边缘在本地决定的。 

这`good_cnt`数组测量导航系统可以沿着最短路径继续行驶的方式。 这对于最大计算量至关重要，因为它决定了是否可以迫使 Polycarp 离开推荐路线。 

在遍历给定路径的过程中，每个步骤都被分类为强制重建（当边缘与任何最短路径不兼容时）或潜在可避免的步骤，其中仅分支确定最大值。 

## 工作示例

 考虑一个小图，其中中间节点和目的地之间存在多条最短路径，并且 Polycarp 有时遵循、有时偏离最短结构。 我们首先计算距目的地的距离，然后根据距离是否减少一来对每个步骤进行分类。 

在示例输入中，在第一次转换时，我们检查移动是否与距离分层一致。 如果不是，最小和最大计数都会立即增加，因为系统必须重建。 在后面的步骤中，即使移动是一致的，替代有效邻居的存在也决定了最大计数是否增加。 

| 步骤| 当前您 | 下一个 v | 距离[u] | 距离[v] | 在最短| 好_cnt[u] | 百万 | MX |
 | ---| ---| ---| ---| ---| ---| ---| ---| ---|
 | 1 | 1 | 2 | 3 | 2 | 是的 | >1 | 0 | 1 |
 | 2 | 2 | 3 | 2 | 1 | 是的 | 1 | 0 | 1 |
 | 3 | 3 | 4 | 1 | 0 | 是的 | 1 | 0 | 1 |

 该迹线显示仅当最短路径转换中存在分支时最小值和最大值如何分歧。 当图形强制使用单个最短连续时，两个值一致。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n, m = map(int, input().split())
    g_rev = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        g_rev[v].append(u)

    k = int(input())
    p = list(map(int, input().split()))

    INF = 10**18
    dist = [INF] * (n + 1)

    t = p[-1]
    q = deque([t])
    dist[t] = 0

    while q:
        u = q.popleft()
        for v in g_rev[u]:
            if dist[v] == INF:
                dist[v] = dist[u] + 1
                q.append(v)

    good_cnt = [0] * (n + 1)
    for u in range(1, n + 1):
        for v in g_rev[u]:
            if dist[v] == dist[u] + 1:
                good_cnt[u] += 1

    mn = mx = 0
    for i in range(k - 1):
        u, v = p[i], p[i + 1]
        if dist[u] != dist[v] + 1:
            mn += 1
            mx += 1
        else:
            if good_cnt[u] > 1:
                mx += 1

    return f"{mn} {mx}"

 ## 边缘情况

 当波利卡普的下一步仍然在最短路径上但不是唯一可能的最短延续时，就会出现关键的边缘情况。 在这种情况下，最小计数不会增加，因为系统可以合作，但最大计数会增加，因为系统可以故意选择不同的有效延续，强制重建。 这种分离完全取决于该节点处的 good_cnt[u] 是否大于 1，即使路径本身保持最短一致。
