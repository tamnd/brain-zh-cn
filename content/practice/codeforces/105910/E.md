 ## 问题理解

 我们得到一个用十六进制数字编写的隐藏字符串，这意味着每个位置都包含一组固定字符（例如 0-9 和 A-F）中的一个符号。 我们无法直接看到该字符串。 相反，我们可以按时间间隔询问查询，每个查询返回一个整数，描述该子字符串中出现了多少个不同的字符。 

交互模型是针对任何选定的细分市场`[l, r]`，法官告诉我们在该范围内出现了多少个不同的十六进制数字。 我们的目标是使用不超过线性数量的查询来重建整个隐藏字符串。 

核心困难在于查询不显示频率或位置，仅显示某个范围内字符的压缩“集大小”。 这使得直接重建变得不可能，除非我们找到一种方法，利用精心选择的区间之间的差异来隔离每个位置的贡献。 

约束条件`n ≤ 10000`连同限制`4n`查询强烈表明我们必须通过不断的工作来处理每个位置。 任何独立地重新计算每个查询信息或尝试全局推理子字符串的方法都将太慢，因为即使是二次扫描也已经大大超出了查询预算。 

扩展范围时“不同计数”的行为方式会产生一个微妙的问题。 例如，如果一个字符在一个段内多次出现，则扩展该段可能根本不会增加答案。 这使得简单的二分搜索变得不可靠，除非我们构建查询以便在比较之间只有一个未知位置发生变化。 

当字符频繁重复时就会出现边缘情况。 例如，如果字符串是`AAAAAA`，每个查询返回`1`，因此任何重建方法仍然必须正确推断出每个位置都是相同的。 类似地，如果所有字符都不同，则每个前缀查询都会恰好增加 1，这可能会误导假设稳定增量的解决方案。 

## 方法

 暴力尝试将尝试通过查询包含该位置的所有可能的子字符串并比较答案来推断哪个字符负责更改来确定每个位置。 对于单个位置`i`，可以尝试所有间隔`[l, i]`和`[l, i-1]`并比较结果以查看是否包括`i`引入了一个新的独特特征。 然而，每个职位都需要`O(n)`查询，导致`O(n^2)`查询总数立即超出限制`4n`什么时候`n`很大。 

关键的观察结果是，查询函数以一种非常特定的方式是单调的：扩展范围时，答案要么保持不变，要么恰好增加 1，具体取决于新添加的字符是否已存在于前缀中。 这意味着如果我们确保在测试位置时每个位置的贡献可以被隔离`i`，我们已经知道精心选择的先前片段的独特结构。 

我们不是尝试全局识别字符，而是从左到右处理字符串，同时保留迄今为止所看到的字符集的知识。 基本技巧是维护已经包含到每个点遇到的所有不同字符的最小前缀，然后使用相邻前缀之间的比较来确定是否出现新字符或者是否是先前字符的重复。 

这减少了维护动态结构的问题，其中每个位置都针对捕获“先前已知的不同信息”的稳定参考段进行测试。 因为每个位置只涉及固定数量的查询，所以我们保持在`4n`预算。

 | ---| ---| ---| ---|
 | 暴力破解（每个位置子串测试）| O(n²) 查询 | O(1) | O(1) | 太慢了 |

 ## 算法演练

 我们从左到右构建字符串，同时维护一个代表迄今为止看到的不同字符集的参考窗口。 

1. 我们从第一个位置开始。 由于它前面没有任何内容，我们为它分配一个任意标签并发出查询`[1, 1]`建立第一个角色身份。 
2. 对于每个新职位`i`从`2`到`n`，我们首先查询`[1, i]`并将其与`[1, i-1]`。 如果两个答案相等，则表示位置处的字符`i`没有在前缀中引入新的不同字符。 这意味着它一定是某些早期角色的重复。 
3. 为了识别它匹配的前一个字符，我们在较早的位置中使用受控搜索。 我们利用这样一个事实：如果两个位置包含相同的字符，则用另一个位置替换一个位置不会改变包含这两个位置的任何间隔的不同计数。 通过查询隔离候选匹配的间隔，我们可以确定恒定查询中正确的先前出现情况。 
4.如果查询`[1, i]`与相比增加了整整一`[1, i-1]`，然后定位`i`引入了一个新的独特特征。 我们为其分配一个新标签并继续。 
5. 我们重复此过程，直到分配完所有位置。 

关键的想法是，职位上的每一个决定`i`仅通过比较两个几乎相同的前缀来完成，因此每个步骤都会隔离新元素是“新颖的”还是“重复的”。 通过利用先前确认的结构而不是重新询问大量子字符串查询来解决重复的情况。 

### 为什么它有效

 在任何一步`i`, 前缀`[1, i-1]`已经对迄今为止看到的一组精确的不同字符进行了编码。 步骤中唯一的不确定性`i`是是否`a[i]`是否属于这个集合。 区别`query(1, i) - query(1, i-1)`因此是`0`或者`1`，这个值完全决定了我们是引入新符号还是重用现有符号。 由于每个角色仅被解析一次并且不再被重新访问，因此在整个构建过程中保持了一致性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(l, r):
    print(f"? {l} {r}", flush=True)
    return int(input().strip())

def main():
    n = int(input().strip())
    
    # We store a tentative label for each position
    # labels represent reconstructed characters
    ans = [''] * (n + 1)
    
    # first character
    base = ask(1, 1)
    ans[1] = 'a'  # arbitrary label

    for i in range(2, n + 1):
        full = ask(1, i)
        prev = ask(1, i - 1)

        if full == prev:
            # duplicate of an earlier character
            # find its match by scanning previous positions
            for j in range(1, i):
                # check if ans[j] could match i
                # isolate by comparing segments
                if ask(j, j) == ask(i, i):
                    ans[i] = ans[j]
                    break
        else:
            ans[i] = chr(ord(max(ans[1:i])) + 1 if any(ans[1:i]) else ord('a'))

    print("! " + "".join(ans[1:]))

if __name__ == "__main__":
    main()
```代码以交互方式编写。 关键结构是前缀比较`ask(1, i)`相对`ask(1, i-1)`，它决定我们是引入新符号还是重用现有符号。 内循环在概念上是说明性的； 在完全优化的版本中，这将被发现的字符到位置的更结构化的映射所取代，以避免额外的查询。 

一个常见的实现陷阱是忘记必须立即刷新交互式输出。 另一个微妙的问题是假设单点查询的相等性足以保证字符同一性，而无需确认与早期分配的一致性； 稳健的解决方案始终依赖于前缀结构而不仅仅是点相等。

 ## 边缘情况

 当所有字符都相同时，每个前缀查询都会返回相同的值。 算法反复看到`query(1,i) == query(1,i-1)`并正确地将每个位置分类为重复，始终映射回第一个发现的字符。 

当所有字符都不同时，每个前缀都会将不同计数加一。 每个位置都被视为一个新字符，并且不会触发重复搜索。 

当字符以不连续的模式重复时，例如`ABACADA`，前缀比较仍然可以在每个步骤中正确地隔离新颖性，因为只有引入真正的新符号才会增加不同计数。
