 ## 解决方案
 ## 问题理解

 给定两个长度相等的字符串，并且允许我们通过交换字符将第一个字符串转换为第二个字符串，但仅限于一个受限规则：我们可以交换索引相差 3 或 4 的位置。每次交换都是免费的，并且可以任意重复多次。 

任务不是直接模拟交换，而是确定是否可以仅使用这些允许的交换将起始字符串重新排列为目标字符串。 

关键的结构问题是当 i 和 i+3 和 i+4 之间存在边时，索引的排列是可以达到的。 这定义了一个关于位置的图，并且交换允许我们在该图的连接组件内自由地排列字符。 所以问题就变成了：两个字符串在由这些边引起的每个连接组件内是否具有相同的多组字符？ 

约束很严格：测试用例的总长度最多为 2⋅10^5，并且最多可以有 10^4 个测试用例。 这迫使每个测试用例都采用本质上线性的解决方案，并且强烈阻止任何在大型隐式图上使用 BFS 或 DFS 为每个位置重新计算图连接性的方法。 

一个天真的心理错误是假设这是一个简单的奇偶性或模块化类问题，例如“具有相同 i mod k 的位置必须匹配”。 这是错误的，因为尺寸 3 和 4 的步长会生成更丰富的连接结构。 

第二个微妙的陷阱是假设邻接是本地的。 例如，仅考虑附近的交换会导致仅检查大小为 4 或 5 的窗口，这在 3 和 4 组合连接远处索引的远程传播等情况下会失败。 

## 方法

 如果我们直接模拟该过程，我们本质上是在探索由 n 个节点图上的交换生成的所有排列，其中边将 i 与 i+3 和 i+4 连接。 每个交换都是一个转置，因此可达状态恰好是该图的连接组件内的排列。 

暴力方法将显式构建图并从每个未访问的节点运行 DFS/BFS 来计算连接的组件。 然后，对于每个组件，比较 s 和 t 中仅限于该组件的多组字符。 

这是正确的，但是显式构建边的成本为 O(n)，而隐式图上的 BFS 成本仍然为 O(n)。 因此每个测试用例的总数是线性的，这原则上是好的。 真正的问题是，每个节点简单地构建邻接列表也是 O(n)，并且重复 T 次仍然可以通过，但有一个更深层次的简化：组件的结构是固定的，并且对于 k=3 是周期性的。 

关键的观察结果是，由边 i↔i+3 和 i↔i+4 导出的图根本不需要 BFS。 我们可以通过推理 3 和 4 如何相互作用来分析确定连通分量。 由于 gcd(3,4)=1，该图在足够大的间隔内变得完全连接，但边界效应对于小指数很重要。 事实上，对于 k=3，结构很快稳定下来，我们可以证明，除了可以明确分类的小型有限前缀结构之外，所有索引都已连接。 

这将问题简化为将索引分组为由可达性确定的少量等价类，而不是每次测试都进行图遍历。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解 BFS 组件 | 每次测试 O(n) | O(n) | 已接受但没有必要 |
 | 最优结构分组 | 总共 O(n) | O(n) | 已接受 |

 ## 算法演练

 交换在索引 1 到 n 上定义一个无向图，只要有效，边就位于 i 和 i+3 以及 i 和 i+4 之间。 每个连接的组件都可以任意重新排列，因此只有每个组件内的多组字符才重要。

1. 在从 1 到 n 的索引上构建 DSU（不相交集并集）。 对于每个 i，如果存在，则将 i 与 i+3 并集，如果存在，则将 i 与 i+4 并集。 这准确地构造了由交换引起的可达性结构。 
2. 在所有并集之后，迭代每个索引并收集其组件的根。 
3. 对于每个分量根，维护两个频率计数器：一个用于 s 中的字符，一个用于 t 中的字符。 
4. 扫描索引时，更新两个字符串的相应分量频率。 
5. 处理完所有位置后，比较每个分量的频率图。 如果全部匹配，则输出YES，否则输出NO。 

这样做的原因是任何交换操作都会保留连接组件内的多组字符，并且 DSU 准确捕获重复交换下索引的等价类。 

### 为什么它有效

 每个允许的交换都是无向图中的一条边，执行交换对应于沿边应用转置。 任何交换序列都不能将字符移出其连接的组件。 相反，在连通组件内，边在该组件上生成完整的对称组，因为沿连通图的转置会生成所有排列。 因此，可到达的配置正是那些保留每个组件的字符多重集的配置，并且 DSU 精确地计算这些组件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra = self.find(a)
        rb = self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

def solve():
    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        s = input().strip()
        t = input().strip()

        dsu = DSU(n)

        for i in range(n):
            if i + 3 < n:
                dsu.union(i, i + 3)
            if i + 4 < n:
                dsu.union(i, i + 4)

        comps = {}
        for i in range(n):
            r = dsu.find(i)
            if r not in comps:
                comps[r] = [0] * 26
            comps[r][ord(s[i]) - 97] += 1
            comps[r][ord(t[i]) - 97] -= 1

        ok = True
        for arr in comps.values():
            if any(x != 0 for x in arr):
                ok = False
                break

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```DSU 对可以通过重复允许的交换连接的索引进行分组。 联合运算显式添加边 (i, i+3) 和 (i, i+4)，匹配问题的交换规则。 

每个组件的频率数组存储净平衡：s 中的字符递增，t 中的字符递减。 如果某个组件完全匹配，则所有值都会取消为零。 

一个微妙的实现细节是使用单个 26 长度数组而不是两个映射。 这使得每个组件的比较复杂度为 O(26)，这实际上是恒定的。

 ## 边缘情况

 一种重要的边缘情况是非常小的字符串，无法进行交换。 当 n < 3 时，图没有边，因此每个位置都是孤立的。 该算法仍然有效，因为 DSU 永远不会合并任何内容，并且每个索引都成为其自己的组件。 s 和 t 之间的任何不匹配都会立即被检测到，因为每个字符必须单独匹配。 

另一种情况是 n 恰好为 3 或 4，其中仅存在单个交换边。 对于 n=3，根本不可能进行交换。 对于 n=4，仅存在 (1,4)，这意味着只能交换端点。 DSU 正确捕获了这一点，因为它仅在索引有效时添加边缘。 

更微妙的情况是，当连通性跨越重叠边缘增长时，例如 n=7，其中 1→4→7 等路径间接连接遥远的索引。 DSU 捕获传递闭包，确保即使是间接可达性也能在没有显式路径搜索的情况下得到考虑。
