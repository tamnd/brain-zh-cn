 ## 解决方案
 ## 问题理解

 我们得到一系列按固定顺序排列的卡片，我们从上到下处理它们。 每张卡要么是英雄，要么是奖金。 英雄卡的价值为零，代表着在我们的军队中最终确定一名英雄的机会。 奖励卡具有正值，可以暂时存储在单独的结构中，但只能以稍后影响英雄的方式存储。 

当英雄卡出现时，立刻就形成了军队中的英雄。 如果此时我们已经存储了任何奖励卡，则我们可以将这些存储的奖励中的一张准确地分配给该英雄，特别是我们仍然选择保留的最近存储的一张。 然后该奖金将被消耗并从存储中删除。 如果没有存储奖金，则英雄贡献为零。 

目标是选择保留或丢弃哪些奖励卡，以便当英雄卡出现时，所有英雄的总分配奖励值最大化。 

所有测试用例的输入大小总共高达二十万张卡，因此任何尝试模拟保留或丢弃奖金的所有子集的解决方案都将立即失败。 即使每个测试用例的二次行为也太慢，因此解决方案必须是线性或接近线性的。 

当奖金丰富但英雄稀少或延迟时，就会出现一个微妙的问题。 例如，如果所有英雄都提早出现，而奖励来得较晚，则即使有很多奖励，也无法使用奖励。 相反，如果英雄来得早，而我们放弃了太多早期的奖励，那么后来的英雄可能会错过高价值的任务。 

当奖金太多时，总是保留所有奖金的简单贪婪会失败，因为只有有限数量的英雄可以使用它们。 例如，如果奖励比英雄多，我们就必须丢弃一些，但选择哪些并不是微不足道的，因为顺序很重要。 

## 方法

 一个蛮力的想法会尝试为每个奖励决定是否保留它，然后模拟按顺序将奖励分配给英雄。 这导致了指数级的选择，因为每个奖励都可以保留或丢弃，并且每个英雄都可以消耗任何可用的存储奖励。 即使进行了修剪，状态空间也会爆炸，因为排序和选择之间的交互会创建许多有效的配置。 

关键的观察结果是，英雄卡的行为就像“消费者”，每一张都从一组已经看到的奖金中获取一份奖金，并且如果可能的话，只应该使用最好的可用奖金。 由于奖金是正数，如果我们正确管理可用性，尽早使用更大的奖金永远不会损害未来的英雄。 困难在于我们可能同时拥有太多奖金，因此我们必须决定保留哪些奖金。 

这成为一个经典的“最大化所选项目的总和，并随着时间的推移开放有限的插槽”问题。 每个英雄有效地创建一个插槽，我们可以在其中附加最多一个从所有先前看到的奖励中选择的奖励。 如果我们反过来思考，每个英雄都希望在其位置之前获得尽可能好的奖励。 

我们不是直接模拟堆栈，而是维护一个候选奖金池，并确保我们只保留未来可以实际分配给英雄的奖金。 自然的结构是处理数组，同时维护奖金的最大结构，并在需要时贪婪地为每个英雄分配最大可能的奖金。 

最重要的见解是，在任何时候，如果我们到目前为止已经看到了一定数量的英雄，我们永远不应该保留超过该数量的奖金，因为额外的奖金永远不会被早期的英雄使用，只能竞争未来的英雄。 这将问题简化为选择最大可能的奖金并将其与英雄贪婪地匹配。

我们可以通过在堆中收集奖金来实现这一点，并且当遇到英雄时，确保我们分配迄今为止最好的可用奖金（如果存在）。 如果我们积累的奖金比迄今为止看到的英雄更多，我们就会丢弃最小的奖金，因为它们最没有用。

 ## 算法演练

 1. 从左到右遍历卡片序列，维护迄今为止遇到的所有奖金值的最大堆（或等效结构）。 这代表当前可分配的所有奖金。 
2. 记录到目前为止已经看到的英雄数量。 每个英雄都代表着一个未来的任务机会。 
3.当我们遇到奖励卡时，将其值插入堆中。 这意味着它可供某些未来的英雄使用。 
4. 如果在任何时候存储的奖励数量超过了目前看到的英雄数量，则从堆中删除最小的奖励。 此步骤确保我们永远不会存储以后无法与英雄匹配的奖金。 被删除的奖金是那些最不可能为最终总金额做出贡献的奖金，因为在任何任务中，更高的奖金都更有价值。 
5. 当我们遇到英雄卡时，增加英雄计数器。 然后，如果堆非空，则从中取出最大的奖励并将其分配给该英雄，并将其添加到总分中。 从堆中删除该奖金，因为它已被消耗。 
6. 继续此过程直至序列结束。 

删除多余的小额奖金背后的原因是，只能使用与英雄一样多的奖金，并且在任何一组可能的任务中，保留较大的奖金占主导地位。 

### 为什么它有效

 在数组的任意前缀处，假设我们已经看到了 h 个英雄和 b 个奖励。 在任何最优策略中，最多可以在前 h 个英雄之间使用 h 个加成。 如果 b 超过 h，则任何最佳解决方案都必须至少放弃 b 减去 h 的奖励。 由于奖金仅在价值上有所不同，并且除了顺序之外没有位置限制，因此丢弃最小的奖金是最佳选择，因为用较大的奖金替换保留的奖金只能提高或保持总和。 这就产生了一个交换论点：任何保留较小奖金而放弃较大奖金的解决方案都可以通过交换它们来改进，而不会违反可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # we store bonuses as negative values for max-heap behavior
        heap = []
        hero_count = 0
        total = 0
        
        for x in a:
            if x == 0:
                hero_count += 1
                if heap:
                    total += -heapq.heappop(heap)
            else:
                heapq.heappush(heap, -x)
                # discard excess small bonuses: keep at most hero_count items
                if len(heap) > hero_count:
                    heapq.heappop(heap)
        
        print(total)

if __name__ == "__main__":
    solve()
```该实现使用负值堆来模拟 Python 中的最大堆。 每个奖励都会在看到后立即插入。 关键的平衡步骤发生在插入之后：如果到目前为止我们的奖金比英雄多，我们会删除最小的奖金，这对应于弹出最大的负值。 

英雄会增加计数并立即消耗最好的可用奖金（如果存在）。 这符合这样的想法：每个英雄在出现时都应该被分配尽可能最强的存储奖励。 

一个常见的错误是延迟分配奖金或在完整的输入处理后尝试将它们配对。 这打破了排序限制，因为出现在英雄之后的奖励不能用于该英雄。

 ## 边缘情况

 当所有英雄出现在任何奖励之前时，堆在英雄处理期间永远不会被使用。 用于输入`0 0 0 5 6`，每个英雄都会找到一个空堆，因此总数仍然为零。 该算法自然地处理这个问题，因为分配仅在堆非空时发生。 

例如，当所有奖励出现在任何英雄之前时`5 4 3 0 0`，先收集所有加成，然后前两个英雄消耗两个最大的值。 堆修剪规则确保没有超出英雄数量的不必要的存储，并且结果成为最佳可用匹配的总和，这是最优的。 

当英雄和奖励紧密交替时，堆可以确保在每个英雄步骤中，我们仍然可以获得之前最好的奖励，即使之前丢弃了多个较小的奖励。 这避免了被早期小值的局部贪婪决策所困。
