[CF 1800C1 - 为英雄提供动力（简单版）](https://codeforces.com/problemset/problem/1800/C1)

 **评分：** 1000
 **标签：** 数据结构，贪心
 **求解时间：** 3m 50s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们从上到下处理一副纸牌。 正值代表奖金卡，而`0`代表一张英雄卡。 

每当我们遇到奖励卡时，我们可能会保留它以备后用，或者将其扔掉。 每当我们遇到英雄卡时，我们可能会给予该英雄最强的可用存储奖励。 该奖励会被消耗并添加到军队总实力中。 如果没有奖金，英雄就没有任何贡献。 

目标是最大化所有英雄获得的总力量。 

输入包含多个测试用例。 对于每个测试用例，我们都会得到牌组顺序，并且必须计算最大可能的总功率。 

这个简单版本的限制很小。 所有测试用例中的卡片总数最多为 5000 张。$O(n^2)$解决方案会很合适，但是有一个更干净的贪婪解决方案可以运行$O(n \log n)$。 

问题的微妙之处在于，奖励只能由牌组中出现在这些奖励之后的英雄使用。 我们不能随意搭配英雄和奖金。 

考虑套牌：```
0 100
```答案是`0`， 不是`100`。 英雄出现在奖励之前，因此无法使用奖励。 

另一个重要案例是：```
5 1 0
```答案是`5`， 不是`6`。 一名英雄只能获得一张奖励卡。 获得这两项奖金是不可能的。 

第三种情况是：```
1 2 3 0 0
```答案是`5`。 第一个英雄应该收到`3`，第二个应该收到`2`。 赠送`1`首先会浪费价值并只生产`4`。 

这些例子表明，每当英雄出现时，我们应该使用最大的可用奖金。 

## 方法

 暴力解决方案将尝试每一个可能的决定，即保留还是丢弃每张奖金卡，以及将存储的奖金分配给英雄的每一种可能的决定。 这会探索呈指数级增长的许多状态，因为每个奖励都会引入多种选择。 即使对于几十张卡，这也是不可行的。 

关键的观察是保留一张奖金卡永远不会有坏处。 如果奖励以后没有用处，我们可以简单地忽略它。 唯一有意义的决定发生在英雄出现的时候。 

假设当前有几张奖励卡可用。 如果我们给英雄除了最大的奖励之外的任何东西，我们可以用最大的选择交换这个选择，并且永远不会减少最终的答案。 当前的英雄获得更多的力量，而未来的英雄仍然可以获得较小的奖励。 

这种交换论点直接导致了贪婪策略。 将所有可用奖金保留在最大堆中。 当英雄出现时，从堆中删除最大的奖金并将其添加到答案中。

 ## 算法演练

 1. 初始化一个空的最大堆并将答案设置为零。 
2. 从左到右处理这副牌。 
3. 如果当前卡牌是正数，则将其值插入堆中，因为此奖励现在可供未来的英雄使用。 
4. 如果当前卡牌是英雄卡牌（`0`），检查堆是否非空。 
5. 如果至少有一项奖金可用，则从堆中提取最大的奖金并将其添加到答案中。 
6. 继续，直到处理完所有卡片。 
7. 输出累计答案。 

### 为什么它有效

 在每张英雄卡上，只能使用之前看到的奖励。 在这些奖励中，选择最大的可用值始终是最佳的。 

假设英雄获得奖金$x$而更大的可用奖金$y$存在。 交换任务，以便当前英雄接收$y$将当前贡献增加$y-x$。 较小的奖金$x$仍然可供后来的英雄使用，因此未来的选择不会变得更糟。 重复这一论点可以消除所有非贪婪选择，并将任何最佳解决方案转变为始终获得最大可用奖金的解决方案。 

由于堆始终准确存储仍然可以分配的奖金，因此提取每张英雄卡的最大值会产生最佳结果。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())
    answers = []

    for _ in range(t):
        n = int(input())
        cards = list(map(int, input().split()))

        heap = []
        total = 0

        for x in cards:
            if x > 0:
                heapq.heappush(heap, -x)  # max-heap
            else:
                if heap:
                    total += -heapq.heappop(heap)

        answers.append(str(total))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```堆存储负值，因为 Python`heapq`实现一个最小堆。 推动`-x`允许最小的存储值对应于最大的原始奖金。 

每张正面卡可用时都会立即插入。 每张英雄卡最多消耗一张奖励，完全符合规则。 

支票`if heap:`这很重要，因为英雄可能会出现在任何奖励卡之前。 在这种情况下，英雄贡献的力量为零。 

答案可能会变大，因为卡牌力量达到$10^9$，因此我们使用 Python 整数累加结果。

 ## 边缘情况

 考虑套牌：```
0 7
```英雄出现在任何奖励卡之前。 处理英雄时，堆是空的，因此不会向答案中添加任何内容。 后面的奖励不能及时倒退。 算法正确返回`0`。 

考虑：```
10 1 0
```当英雄出现时，两种奖励都可用。 堆包含`{10,1}`并且该算法删除了`10`。 答案就变成了`10`。 服用`1`相反，将永久失去九个单位的力量。 

考虑：```
5 4 3 0 0 0
```第一个英雄收到`5`，第二个接收`4`，第三个接收到`3`。 答案就变成了`12`。 堆自然地将最强的剩余奖励匹配给每个连续的英雄，这正是最佳分配。
