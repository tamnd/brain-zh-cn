[CF 1800E2 - 不可饶恕的诅咒（硬版）](https://codeforces.com/problemset/problem/1800/E2)

 **评分：** 1500
 **标签：** 暴力破解、构造性算法、dfs 和类似算法、dsu、图、贪婪、字符串
 **求解时间：** 2m 20s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们有两个长度相等的字符串，`s`和`t`。 开始于`s`，我们可以重复交换位置完全不同的字符`k`或者确切地说`k + 1`。 问题是这些允许的交换是否足够强大以实现转型`s`进入`t`。 

该操作很不寻常，因为我们不允许交换任意位置。 允许的交换定义了字符串位置的图表。 位置`i`连接到位置`j`如果`|i - j| = k`或者`|i - j| = k + 1`。 每次交换都沿着该图的一条边发生。 

字符串的长度可以达到`2 · 10^5`，所有测试用例的总长度也是`2 · 10^5`。 任何检查所有位置对的算法都会被立即排除。 我们需要每个测试用例接近线性时间。 

一些边缘情况很容易被忽略。 

考虑：```
n = 5, k = 4
s = "abcde"
t = "ebcda"
```这些字符串包含完全相同的字母。 仅频率检查就会说“是”。 但立场`0`只能交换位置`4`，同时位置`1`,`2`， 和`3`被孤立。 由于中间位置无法移动，因此即使字符数匹配，答案也可能是“否”。 

当图连通时会出现另一个重要情况。```
n = 7, k = 1
```允许的距离是`1`和`2`。 距离`1`已经连接了相邻位置，因此每个排列都变得可达。 在这种情况下，只有多组字母才重要。 

第三个陷阱是假设没有由边连接的位置是不可移动的。 连接性很重要，而不是直接的边缘。```
n = 5, k = 3
```职位`0`和`4`不是直接连接的，而是通过中间顶点属于同一个连通分量。 角色可以经历一系列的交换。 

## 方法

 暴力解决方案将显式构造所有可到达的字符串`s`在排列的状态空间上使用 BFS。 这是正确的，因为每个有效的转换都对应于一系列交换。 不幸的是，即使对于温和的`n`，可达状态的数量呈阶乘增长。 长度为 20 的字符串已经拥有比任何程序可以探索的更多的状态。 

关键的观察结果是该操作仅作用于头寸。 实际字母并不影响哪些掉期是合法的。 

将位置视为图形的顶点。 我们在之间添加一条边`i`和`j`每当`|i-j| = k`或者`|i-j| = k+1`。 任何允许的交换都会跨一条边交换字符。 

在该图的连接组件内，任意排列是可能的。 其边允许交换的连通图会生成其顶点的所有排列。 角色可以沿着路径路由，因此可以实现组件内的每个重新排列。 

这彻底改变了问题。 我们不需要搜索字符串，而只需要确定位置图的连通分量。 

对于每个连接的组件，来自的多组字母`s`必须匹配所需的多组字母`t`。 如果每个组件都满足这个条件，则转换是可能的。 否则就不是。 

该图仅包含`O(n)`边，因为每个顶点最多有四个邻居，对应于`±k`和`±(k+1)`。 这允许线性时间 DFS 或 DSU 解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对可达字符串的暴力破解 | 指数| 指数| 太慢了 |
 | 连接组件 + 频率检查 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 构建仓位图表`0 ... n-1`。 
2. 对于每个位置`i`，尝试将其与`i+k`,`i-k`,`i+k+1`， 和`i-k-1`每当这些职位存在时。 
3. 使用 DFS、BFS 或 DSU 查找所有连接的组件。 
4. 对于每个组件，收集`s`位于该组件中。 
5.收集角色`t`位于同一组件中。 
6. 对两个集合进行排序并进行比较。 
7. 如果任何组件产生不同的多重集，则输出`"NO"`。 
8. 如果每个组件都匹配，则输出`"YES"`。 

第 6 步有效的原因是，在一个连接的组件内，我们可以任意排列字符。 唯一不变的是该组件内存在每个角色的副本数量。 

### 为什么它有效

 每次交换都会保留包含每个位置的连接组件。 角色永远无法离开其组件，因为每个允许的移动都沿着该组件内部的边缘发生。 

因此，对于每个组件，其中包含的字母多集都有该过程的不变量。 

反之亦然。 由于沿连通图的边的相邻交换会生成该图中顶点的每个排列，因此可以实现组件字母的任何排列。 一旦多重集逐个匹配，我们就可以独立地重新排列每个组件以匹配目标字符串。 

分量多重集条件是充分必要的，证明了其正确性。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        target = input().strip()

        adj = [[] for _ in range(n)]

        for i in range(n):
            for d in (k, k + 1):
                j = i + d
                if j < n:
                    adj[i].append(j)
                    adj[j].append(i)

        vis = [False] * n
        ok = True

        for start in range(n):
            if vis[start]:
                continue

            q = deque([start])
            vis[start] = True
            comp = []

            while q:
                v = q.popleft()
                comp.append(v)

                for to in adj[v]:
                    if not vis[to]:
                        vis[to] = True
                        q.append(to)

            a = sorted(s[i] for i in comp)
            b = sorted(target[i] for i in comp)

            if a != b:
                ok = False
                break

        ans.append("YES" if ok else "NO")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```图构造仅添加前向边缘。 由于每条边都在两个方向上插入，因此图保持无向并且连通分量搜索正常工作。 

一个常见的错误是仅检查全局字符频率。 硬版本的存在正是因为相等的总体频率是不够的。 每个连接的组件必须单独检查。 

另一个常见的错误是尝试构建所有`O(n²)`距离为的对`k`或者`k+1`。 每个顶点只有固定数量的有效邻居，因此我们可以在线性时间内构建图。

 ## 边缘情况

 当`k = 1`，每个位置都与其邻居相连。 图形变得连通。 例如：```
n = 5
s = abcde
t = edcba
```所有位置都属于一个组件。 字符多重集匹配，所以答案是`"YES"`。 

什么时候`k`规模非常大，很多仓位都变得孤立。```
n = 5
k = 4
s = abcde
t = aecdb
```位置`1`包含`b`在`s`但`e`在`t`。 自位置`1`是一个孤立的组成部分，该特征不能改变。 组件检查立即拒绝转换。 

当组件包含多个顶点时，即使没有直接边缘，字母也可能会穿过中间位置。```
n = 5
k = 3
```该图通过路径连接。 角色可以通过多次交换从一端移动到另一端。 该算法正确地将整个图视为一个组件，并仅比较组件范围的多重集。
