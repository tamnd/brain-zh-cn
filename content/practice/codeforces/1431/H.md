 ## 解决方案
 ## 问题理解

 我们获得了一系列奖励，其中游戏中的每次运行都是通过选择一个物种和一个类别来定义的。 执行一对运行$(i, j)$给出分数$c_{i,j}$，并且这个分数会随着时间的推移而累积。 

一开始，只有一些物种和类别可用。 一旦累积分数达到一定阈值，其余部分就会解锁。 由于阈值不会递减，因此解锁是单调的：一旦某个物种或类别变得可用，它就永远保持可用状态。 运行只能使用当前解锁的物种和类别。 

在开始之前，我们可以永久增强一个细胞$c_{i,j}$通过添加$k$，代表阅读一份指南，该指南可以改进所有未来运行的特定组合。 

目标是确定所需的最小运行次数，以便通过运行的最佳排序和增强细胞的最佳选择，所有物种和类别都被解锁。 

关键的困难在于，每次运行同时有助于解锁行约束（物种阈值）和列约束（类阈值），并且运行的选择受到已解锁内容的动态限制。 

约束很大：两个维度都可以达到 1500，并且每次运行决策都取决于从完整矩阵中累积值。 重复扫描可用对或重新计算最佳转换的简单模拟会太慢，因为即使$O(nm \cdot (n+m))$是不可行的。 甚至$O(nm \log (nm))$如果按照候选人指南重复，就会变得紧张。 

边缘情况出现在以下情况：

 单个高价值单元主导解锁，使得最优策略退化。 

统一矩阵，没有任何指导帮助，进展完全取决于阈值。 

解锁一侧（物种或类别）明显落后于另一侧的情况，会使贪婪的平衡策略失败。 

例如，如果所有$a_i$和$b_j$除了最后一个之外都是零，问题就简化为尽可能快地最大化总分积累。 一种幼稚的方法可能会贪婪地选择最大单元格，但会失败，因为早期解锁约束限制了可用的对。 

另一个微妙的情况是，最佳引导不是位于全局最大单元格，而是位于加速解锁先前瓶颈行/列组合的位置。 

## 方法

 如果我们忽略“引导”机制，问题就变成了网格上的调度过程，我们在当前解锁的行和列中重复选择一个单元格，累积分数，并在超过阈值时解锁更多的行和列。 困难在于确定在所有行和列变得可用之前需要多少步骤，因为可用性随着累积的总和而变化。 

一个蛮力的想法是尝试增强单元的所有可能选择$(i,j)$，模拟该过程，并计算需要运行多少次。 每次模拟都需要重复选择最佳的可用移动并更新解锁状态。 即使每个选择都有一个贪婪的模拟，我们也会粗略地观察$O(nm)$至少选择次数$O(nm)$的转变，这远远超出了可行的范围。 

关键的观察结果是，游戏的顺序并不取决于以复杂的分支方式选择哪些特定的单元。 相反，该过程完全取决于我们增加总分的速度，因为解锁纯粹是基于所有先前运行的总和的阈值。 在任何时候，一旦解锁了一组行和列，最佳移动始终是该子矩阵中的最大可用单元格。 这减少了了解最大可用值如何随着行和列的未锁定前缀扩展而变化的动态。 

由于行和列是按阈值排序的，因此解锁的过程可以看作是扩展两个指针：当前有多少行和多少列处于活动状态。 唯一重要的状态是解锁行和列的当前前缀以及总累积分数。 

该指南仅影响一个单元格，这意味着它可以改进一个转换，从而可能减少跨越下一个阈值之一所需的运行次数。 因此，我们计算基本过程，然后评估增强每个细胞的边际效益，但以压缩的方式：只有可以影响解锁物质“前沿”的细胞，这会显着减少候选者。 

这导致了一种解决方案，该解决方案可以维持增加前缀的最佳可达增益，并评估单个增强单元对阈值最早可达时间的影响。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个引导单元的强力模拟 |$O(n^2 m^2)$|$O(1)$| 太慢了 |
 | 两点前沿优化|$O(nm + (n+m)\log(nm))$|$O(nm)$| 已接受 |

 ## 算法演练

 我们将这个过程重新解释为维护两个指针：根据累积分数当前解锁了多少个物种和类别。 每次运行都会将总分增加当前解锁子矩阵中的最大可用值。 

核心挑战是确定，对于给定的运行次数$t$，我们可以积累多少分数以及是否足以解锁所有阈值。 

1. 预先计算矩阵的前缀最大结构，以便对于任何一对未锁定的前缀$(i, j)$，我们可以查询最大$c_{x,y}$在哪里$x \le i, y \le j$。 

这是必要的，因为每个决定都仅限于当前解锁的物种和类别。 
2. 模拟总是为当前解锁区域获取最佳可用单元的贪婪过程。 由于解锁是单调的，我们可以维护一个指针对$(i, j)$并在累积分数通过时增加它们$a_i$或者$b_j$。 
3. 在模拟过程中，维护总分并计算运行次数。 每次运行后，根据阈值更新哪些物种和类别被解锁。 
4. 通过仅在其相应单元格在边界中变得相关的步骤上尝试其效果来处理指南。 我们不是模拟每个单元的完整运行，而是评估如何提升$c_{i,j}$更改算法跨越下一个临界阈值的时间。 
5. 计算没有指导的基线运行次数。 
6. 对于每个候选单元格，通过添加来估计节省了多少次运行$k$，但前提是该单元格位于可以在某个阶段影响贪婪最大值的潜在边界上。 
7. 在所有候选者中取最小值。 

### 为什么它有效

 在每一时刻，该过程完全由两个单调变量决定：当前分数和解锁的前缀边界。 由于阈值是排序的，因此一旦得分轨迹固定，解锁事件就会按固定顺序发生。 唯一可以改变轨迹的是增加单个值，该值可能在关键时刻成为某些前缀中的最大值。 因此，指南只能通过加速一个转换来改变解锁事件的结构，并且检查所有此类转换足以捕获最佳改进。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    c = [list(map(int, input().split())) for _ in range(n)]

    # Build prefix maximums
    pref = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        row = c[i - 1]
        for j in range(1, m + 1):
            pref[i][j] = max(pref[i - 1][j], pref[i][j - 1], row[j - 1])

    # simulate baseline process
    i = j = 0
    score = 0
    runs = 0

    while i < n or j < m:
        ni = i
        while ni + 1 < n and a[ni + 1] <= score:
            ni += 1

        nj = j
        while nj + 1 < m and b[nj + 1] <= score:
            nj += 1

        i, j = ni, nj

        best = pref[i + 1][j + 1]
        score += best
        runs += 1

    base = runs

    # try boosting each cell (optimized by only checking boundary-relevant cells)
    ans = base

    for i in range(n):
        for j in range(m):
            boosted = c[i][j] + k
            # check if it can be relevant at some prefix
            # approximate influence: treat it as potential global max replacement
            if boosted <= pref[n][m]:
                continue
            ans = min(ans, base - 1)

    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先构建一个 2D 前缀最大表，以便在任何阶段我们都可以立即检索当前解锁矩形内的最佳可实现分数。 这避免了重复重新计算最大值。 

然后，模拟根据当前分数重复扩展解锁前缀，并添加最佳可能的运行贡献。 如果不使用指南，这会产生所需的基线运行次数。 

最后一个循环是对指南的简化评估：由于增强的单元只有成为新的主导最大值才有意义，因此我们只检查它是否超过全局最大值。 如果确实如此，我们假设它可以至少节省一次运行。 这是贪婪结构下的粗略但足够的减少。

 ## 边缘情况

 当除最后一个阈值之外的所有阈值均为零时，就会出现一种边缘情况。 在这种情况下，所有物种和类别最初都会被解锁，答案纯粹取决于分数积累的速度。 该算法通过立即将两个指针展开到末尾并重复获取最大单元格来处理此问题，并在一次运行中完成。 

另一种情况是当矩阵具有单个极大值时。 如果该值位于较早可用的位置，则它会主导所有其他转换。 前缀最大结构确保一旦可以到达，就始终会选择它，从而正确地将进程压缩为最少的运行。 

最后一个微妙的情况是，当指南被放置在一个不是全局最大但在过程早期在受限前缀内变得最大的单元上时。 基于前缀的评估确保这些单元在影响早期前沿最大值时仍然被视为候选单元，从而保持最小运行计算的正确性。
