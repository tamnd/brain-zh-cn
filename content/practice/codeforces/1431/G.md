 ## 解决方案
 ## 问题理解

 我们得到一个不同整数的集合。 游戏按顺序进行，每轮消除两个数字，并将它们的差值转换为分数。 玩家之间的交互是不对称的：爱丽丝首先选择，但她被限制获取当前最大元素，而鲍勃对爱丽丝的选择做出反应，必须选择一个严格大于爱丽丝选择的数字。 一旦两个数字都被选择，它们就会消失，并且分数会增加鲍勃的值减去爱丽丝的值。 这种情况会重复固定轮数，并且两名玩家都会以相反的目标进行最佳比赛。 

这个过程的微妙之处在于，Alice 并不是简单地选择任意对，而 Bob 也不是以固定的方式贪婪地配对。 相反，每一轮都是一个受约束的对抗性配对过程，取决于剩余的多重集。 

输入大小足够小，二次甚至稍微超二次的方法都是可行的。 和$n \le 400$，三次动态规划解决方案仍然是可以接受的。 这立即表明该问题并不意味着一步一步地贪婪地模拟，而是通过仔细推理间隔或排序位置上的最佳子结构来解决。 

幼稚的模拟会在每次删除后反复尝试重新计算两个玩家的最佳响应。 即使每一轮都是$O(n)$，这样做是为了$k \approx n/2$回合导致$O(n^2)$，但真正的问题是每个决策都不是局部贪婪的。 早期几轮中爱丽丝的选择会影响以后是否可能出现某些高价值的配对。 天真的贪婪“总是配对最接近的较大元素”策略失败了，因为它忽略了全局结构。 

一个典型的失败案例是，尽管早期在本地配对看起来有利可图，但应该保留大量数量以供以后配对。 

例如，考虑：```
n = 6, k = 2
a = [1, 2, 3, 100, 101, 102]
```贪婪的方法可能会尝试将 (1,2) 和 (3,100) 配对，而不使用 (101,102)，从而尽早产生较小的收益。 然而，最佳游戏更喜欢构建对，以便以最大化轮次差异而不是局部差异的方式使用最大值。 

关键的困难是鲍勃总是在爱丽丝之后做出反应，所以爱丽丝实际上是在选择一个“枢轴”，而鲍勃被迫选择它上面的东西，但鲍勃正在最小化结果。 这将问题转化为约束下的全局匹配问题。 

## 方法

 如果我们忽略最佳游戏，一个暴力的想法就是模拟爱丽丝选择和鲍勃响应的每个可能的序列。 在每一步中，爱丽丝都会选择任何有效的元素，而鲍勃则以任何有效的更大元素进行响应。 删除两者后，我们递归。 分支因子大致为$O(n^2)$每一步和深度是$k$，这使得即使对于$n=20$。 

蛮力的失败来自于多次重新计算等效状态。 关键的观察结果是，元素的实际身份仅通过它们的排序顺序起作用，而不是它们的原始标签。 排序后，游戏完全取决于保留哪些元素以及它们如何配对。 

这表明在排序数组的间隔上进行动态编程。 我们不考虑绝对值，而是考虑排序顺序的索引。 每一步都会从爱丽丝选择的右侧删除两个元素，一个是由爱丽丝选择的，一个是鲍勃强制的。 

核心观点是，鲍勃的最佳响应始终是选择仍然大于爱丽丝选择的最小可用元素。 如果他选择一个更大的，他只会增加分数，这对他来说是不利的。 这显着降低了不确定性：一旦爱丽丝选择了位置$i$，鲍勃的反应是确定的。 

现在问题变成：选择$k$对$(i, j)$这样$a_j > a_i$，限制条件是移除它们后，剩余的结构允许进一步优化配对。 挑战在于选择在各轮中相互作用。 

我们通过前缀 DP 来解决这个问题：我们对数组进行排序，并根据使用的元素数量以及从后缀形成的对数来定义状态，从而维护有效保留的“未配对”元素数量。 转换模拟跳过元素或形成强制对。 

这导致了一个经典的DP，我们决定左边有多少元素作为Alice的选择，右边有多少元素作为Bob的响应，确保尊重可行性约束。 

由此产生的结构是$O(n^3)$尝试对剩余元素进行所有分割的 DP。

 ## 算法演练

 我们首先对数组进行排序，以便所有约束都减少为索引比较而不是值比较。 

1. 对数组进行递增排序，以便 Bob 在位置上为 Alice 选择任何有效的选择$i$必须来自右侧。 
2. 定义一个表示前缀上的子问题的 DP 状态，我们在其中跟踪仍有多少元素可用以及仍需要形成多少对。 
3. 对于每个状态，考虑两个结构决策：要么我们暂时保留一个未使用的元素，要么我们将其提交为 Alice 在未来配对中的选择。 
4.当我们选择Alice在位置的元素时$i$，我们必须将 Bob 的响应指定为大于它的最小可用元素。 这立即决定了分数贡献。 
5. 我们通过删除两个元素并减小问题规模来进行转换，将差异累积到 DP 值中。 
6. 我们确保准确执行$k$这样的配对，因此 DP 强制执行计数约束。 

查看同一过程的一种更清晰的方法是考虑构建$k$通过从左到右扫描并贪婪地将每个选定的 Alice 元素与最早可能的有效 Bob 元素进行配对，但允许 DP 决定哪些元素成为 Alice 选择的元素。 

### 为什么它有效

 关键的不变量是，一旦元素被排序，考虑到爱丽丝的选择，鲍勃的最佳响应是确定的。 这消除了状态空间中的对抗性分支。 因此，每个 DP 状态仅代表哪些元素充当 Alice 枢轴的组合选择。 由于Bob总是选择最小的有效响应者，任何偏差只会增加他的损失，因此没有最佳策略需要考虑多个Bob选择。 这将游戏分解为选择有效的匹配结构，并且 DP 枚举所有可行的结构而不会重复计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    # dp[i][j] = best score using first i elements forming j pairs
    # interpreted in structured selection form
    dp = [[-10**18] * (k + 1) for _ in range(n + 1)]
    dp[0][0] = 0

    for i in range(n + 1):
        for j in range(k + 1):
            if dp[i][j] < 0:
                continue

            if i < n:
                dp[i + 1][j] = max(dp[i + 1][j], dp[i][j])

            if j < k and i < n:
                # try making a pair where i is Alice
                # and choose Bob from some later position t > i
                for t in range(i + 1, n):
                    if j + 1 <= k:
                        dp[t + 1][j + 1] = max(
                            dp[t + 1][j + 1],
                            dp[i][j] + a[t] - a[i]
                        )

    print(dp[n][k])

if __name__ == "__main__":
    solve()
```DP 表跟踪我们如何使用排序数组。 第一个转换跳过一个元素，这意味着它不用作 Alice 选择。 第二个转换通过选择左端点并将其与稍后有效的右端点配对来形成一对，从而为分数带来差异。 

三重结构确保我们隐式地尊重排序约束：一旦我们从$i$到$t+1$，它们之间的所有元素都在配对结构中被有效消耗，从而防止重用。 

关键的实现细节是DP索引$t+1$编码鲍勃在位置的选择$t$删除该元素并完成配对，而不会重新访问中间元素。

 ## 边缘情况

 一个关键的边缘情况是元素紧密排列时，例如连续整数。 在这种情况下，贪婪配对似乎是最优的，但仍然需要 DP 以确保早期配对决策不会阻碍更好的全局结构。 

例如：```
n = 5, k = 2
a = [1, 2, 3, 4, 5]
```A naive strategy might pair (1,2) and (3,4), leaving 5 unused. 该算法探索所有有效的跳转结构并确认这是最佳的。 

另一种边缘情况是存在一个非常大的元素时。 最佳策略通常避免过早配对，因为它可以根据结构为多个候选 Alice 选择提供服务。 The DP ensures that it is only used when it yields maximal marginal benefit.

 最后，具有均匀间隔值的情况证实了 DP 不依赖于值大小，而纯粹依赖于排序，这对于正确性至关重要。
