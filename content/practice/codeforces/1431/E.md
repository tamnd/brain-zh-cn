 ## 解决方案
 ## 问题理解

 我们有两支同等规模的球队，每个球员都有固定的技能值。 一场比赛是通过将第一队的每位球员与第二队的一名不同球员配对而形成的，因此该配对是第二队的索引的排列。 

对于任何这样的配对，我们都会查看每场比赛并计算配对球员之间的绝对技能差异。 整个配对的质量由其最弱的匹配决定，这意味着我们采用所有配对的最小绝对差值。 目标是构建一个配对，使最弱的匹配尽可能强大。 

简单来说，我们并不是试图最大化总差异或平均差异。 我们正在努力避免任何“太接近”的比赛。 我们想要排列排列，以便即使是最相似的对也尽可能不同。 

约束足够小，对两个数组进行排序并为每个测试用例执行线性或近线性工作就足够了。 所有测试的 n 总和最多为 3000，因此每个测试用例的 O(n^2) 解决方案已经是安全的，并且 O(n log n) 解决方案是最佳的。 

一个幼稚的错误是贪婪地匹配最接近的值，认为这会减少联系。 这实际上起到了相反的作用：配对最接近的值可以最大限度地减少局部差异，但通常会在其他地方产生至少一个非常小的间隙。 另一个错误的直觉是贪婪地最大化每个个体差异，这也会让你陷入一种配置，其中一对被迫非常接近。 

例如，考虑`a = [1, 10, 20]`,`b = [2, 11, 21]`。 如果我们贪婪地匹配最接近的，我们就会得到差异`1, 1, 1`，所以最小值为 1。但是这里不可能有更好的安排，这表明局部选择强烈限制全局最小值。 

核心困难在于，改善一对可能会加剧其他地方的最小差距，因此我们需要一个结构化的全球策略。 

## 方法

 暴力解决方案尝试第二组的每种排列并计算每个排列的最小绝对差。 这是正确的，因为它评估所有可能的配对，但有 n！ 排列。 即使对于n = 12这也已经是不可行的，而这里n可以是3000，所以这是完全不可能的。 

更结构化的想法来自于思考什么决定了最小绝对差异。 假设我们固定一个候选阈值 x 并询问是否可以构建完美匹配，使得每对都满足 |a[i] - b[p[i]]| ≥x。 如果我们可以有效地检查这一点，那么我们就可以搜索最大 x。 

这将问题转化为可行性问题。 一旦 x 固定，每个元素 a[i] 只能与 b 中 ≤ a[i] - x 或 ≥ a[i] + x 的值匹配。 禁区是a[i]周围的区间，我们需要完全避开它。 

一个关键的观察结果是两个数组都已排序。 这使我们能够在保持可行性的同时贪婪地分配匹配。 如果我们按顺序处理 a[i] 并始终尝试将其与最小的有效 b 或最大的可用有效 b 相匹配，我们就可以保持正确性，因为未来的约束只会变得更严格。 

然而，这仍然留下了如何在不进行二分搜索的情况下直接构造最佳配对的问题。 最后的见解是，我们希望最大化最小间隙，这相当于以一种避免“紧密交错”意义上重叠的方式分隔两个数组。 最佳构造是以结构化方式尝试两个排序数组之间的所有旋转：我们将 b 分成两半并交错极值，以便小值与远值配对。 

对于这个问题，一个更直接和标准的构造是对两个数组进行排序，然后尝试将所有 k 的 a[i] 与 b[(i + k) % n] 匹配，但我们不需要测试所有 k。 相反，最佳配对来自于对两个数组进行排序，然后在受控循环移位中将最小与最大配对，以确保最大分离。 

一个更简单且正确的构造策略是：按排序顺序尝试 b 的所有可能的移位，计算 O(n) 中的最小差异，并选择最佳移位。 由于 n 总共最多为 3000，因此 O(n^2) 就可以了。 

这是有效的，因为任何最佳排列都可以转换为排序序列上的循环移位对齐，而不会恶化最小间隙。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力排列 | O(n!) | O(n) | 太慢了 |
 | 排序后尝试所有循环移位 | 总共 O(n^2) | O(n) | 已接受 |

 ## 算法演练

 1. 对数组 a 和 b 进行排序。 排序至关重要，因为只有相对顺序才能影响绝对差异。 
2. 修复索引移位 k，这意味着我们将 a[i] 与 b[(i + k) mod n] 进行匹配。 这会为每个 k 生成一个有效排列，覆盖包含最佳匹配的结构化匹配子集。 
3. 对于每个移位 k，计算所有对的最小绝对差。 这直接评估匹配的质量。 
4. 跟踪给出这些最小值中最大值的移位 k。 这确保我们选择尽可能避免最接近匹配的配对。 
5. 输出最佳移位对应的排列。 

我们循环移位而不是任意排列的原因是排序数组具有单调结构，并且最佳排列中最差的对总是出现在两个对齐的排序序列之间的边界处。 这些界限所在的地方正在发生变化。 

### 为什么它有效

对两个数组进行排序后，任何排列都可以被视为以尊重相对顺序的方式配对位置。 最小绝对差由两个排序序列之间的“相邻交叉点”控制。 循环移位足以枚举这些序列的所有不同的相对对齐。 在这些比对中，一种实现了全局最优，因为任何最佳配对都可以转化为旋转而不增加最小对距离，因为改进一个交叉仅取决于相对排序，而不是索引的绝对同一性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort()
        b.sort()

        best_k = 0
        best_val = -1

        for k in range(n):
            cur = 10**18
            for i in range(n):
                diff = abs(a[i] - b[(i + k) % n])
                if diff < cur:
                    cur = diff
                    if cur <= best_val:
                        break
            if cur > best_val:
                best_val = cur
                best_k = k

        res = [b[(i + best_k) % n] for i in range(n)]
        pos = {v: [] for v in b}
        for i, v in enumerate(b):
            pos[v].append(i)

        used = [False] * n
        ans = [0] * n

        for i in range(n):
            target = res[i]
            idx = pos[target].pop()
            ans[i] = idx + 1

        print(*ans)

if __name__ == "__main__":
    solve()
```该实现首先对两个数组进行排序，以便所有有意义的结构都按顺序排列，而不是按原始索引排列。 然后，它尝试第二个数组相对于第一个数组的每个循环移位，并评估每个移位的最小差异。 当当前候选班次无法击败最佳班次时，一个小的优化就会提前中断。 

一旦找到最佳移位，我们就通过将移位顺序中的位置与原始索引匹配来重建排列。 由于值可能会重复，因此我们将每个值的所有索引存储在列表中，并在使用时弹出它们。 

一个微妙的实现细节是处理 b 中的重复项。 由于不能保证值是不同的，因此我们无法在不存储多次出现的情况下将值直接映射到索引。 这就是为什么我们为每个值维护一个列表。

 ## 边缘情况

 一种边缘情况是两个数组中的所有值都相同。 在这种情况下，每个配对的最小差异为 0，并且任何排列都是有效的。 该算法仍然评估所有移位并正确返回任意有效移位，无需特殊大小写。 

另一个边缘情况是 b 中存在重复项。 由于我们存储每个值的索引，因此每次出现都只使用一次，因此即使值重复多次，重建仍然有效。 

最后的边缘情况是最佳匹配不是身份转换。 例如`a = [1, 100, 200]`,`b = [50, 51, 52]`。 身份转换给出的最小差异为 49，但转换可以根据对齐方式保留或改进此差异。 该算法评估所有循环对齐并自然地选择最好的一个。
