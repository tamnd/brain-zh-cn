 ## 解决方案
 ## 问题理解

 我们收到一系列聊天消息，仅包含两种类型：客户问题和支持答案。 对话是按时间顺序写的，第一条消息总是一个问题。 

我们关心的唯一结构规则是每个问题都必须由其后的答案“解释”。 每个答案都应该回应一些先前提出的问题，并且答案可以延迟或交错，但如果没有先前未匹配的问题，它们就不可能存在。 换句话说，在对话的任何时刻，我们得到的答案绝不能多于迄今为止出现的问题，并且最终所有问题都必须与答案相匹配。 

任务是针对每个测试用例确定这样的序列在这些规则下是否有效。 

约束很小：最多 500 个测试用例，每个字符串的长度最多为 100。这意味着即使每个测试用例解决方案的 O(n²) 或 O(n) 速度也相当快。 我们只需要跟踪每个测试的一个小的运行状态。 

一个天真的错误是假设每个问题后面都必须紧跟着一个答案。 例如，即使第二个答案被延迟，字符串“QQAA”也是有效的，因为答案可以分组并且不必直接跟随其匹配的问题。 

另一个微妙的失败案例是答案出现在足够多的问题出现之前。 例如，“QAQ”是无效的，因为在消耗“QA”之后，下一个“Q”会增加待处理的问题，但我们永远不会确保前面的答案以一致的结构正确配对，从而在最后留下了一个不匹配的问题。 

关键的隐藏约束是前缀有效性：在每个前缀处，答案不得超过问题，并且最后计数必须相等。 

## 方法

 强力解释将尝试将每个答案与先前未匹配的问题显式匹配，可能使用堆栈或显式跟踪对。 对于每个答案，我们都会向后搜索可用的问题，将其标记为已使用，然后继续。 这是正确的，但不必要地繁重，因为它涉及每个字符的重复扫描或簿记，如果列表或重复搜索实施不当，可能会导致 O(n²) 行为。 

简化一切的观察是我们不关心每个答案属于哪个具体问题。 唯一的要求是答案永远不会超过任何前缀中的可用问题。 这将整个问题简化为维护一个计数器：当前未回答问题的数量。 

我们为每个“Q”增加计数器。 对于每个“A”，我们将其递减。 如果在任何时候它变成负数，则意味着我们试图回答一个尚不存在的问题，这是无效的。 最后，如果我们从未变成负数，那么该结构就是有效的。 

这实际上是类似于括号验证的平衡条件，其中“Q”的行为类似于左括号，“A”的行为类似于右括号，但有一个变化，即可以任意延迟关闭。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力匹配| O(n²) | O(n) | 已接受但没有必要 |
 | 计数器追踪 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.初始化一个计数器`pending = 0`代表有多少问题尚未得到解答。 
2. 从左到右遍历消息字符串。 
3. 如果当前字符是“Q”，则递增`pending`因为出现了一个新的未解答的问题。 
4. 如果字符是“A”，则减1`pending`因为一个答案会消耗一个先前提出的问题。 
5. 如果在任何时候`pending`变为否定，立即断定对话无效，因为出现的答案没有相应的先前问题。 
6. 处理完整字符串后，如果满足则输出“Yes”`pending == 0`，否则输出“No”。 

### 为什么它有效

 在字符串的任意前缀处，`pending`准确地表示未来仍需要答案的问题数量。 答案必须与之前的问题相对应的规则相当于要求该计数永远不会低于零。 如果它确实低于零，则某些答案没有可附加的可用问题。 如果它仍然是非负数但结果是正数，则意味着某些问题从未得到解答，这也违反了要求。 

这个不变量确保了正确性：每个有效序列始终保持非负平衡，任何违反该平衡的行为都精确对应于无效的对话结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    
    pending = 0
    ok = True
    
    for ch in s:
        if ch == 'Q':
            pending += 1
        else:
            pending -= 1
            if pending < 0:
                ok = False
                break
    
    print("Yes" if ok and pending == 0 else "No")
```实现直接遵循计数器逻辑。 早期中断很重要，因为一旦检测到无效前缀，进一步的处理就无法恢复有效性。 最终检查确保没有任何问题未得到解答。 

这里一个常见的差一风格错误是忘记确保最终余额为零。 一个序列可以自始至终保持有效性，但仍然会留下遗留问题，这些问题必须被拒绝。

 ## 边缘情况

 一个边缘情况是一个问题。 输入“Q”保持`pending = 1`并且永远不会减少它，因此最终检查失败，正确拒绝它。 

另一种是在问题较多的前缀之后首先出现答案。 对于输入“QQAQA”，计数器在最终前缀之前保持有效，但仍以正数结束，正确地将其标记为无效。 

一个更微妙的情况是像“QAQAQA”这样的交错。 计数器在1和0之间交替，但永远不会变成负数，并以零结束，因此它是有效的。 这证实了该算法不需要对答案进行分组，只需要保持平衡。
