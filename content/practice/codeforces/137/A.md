 ## 解决方案
 ## 问题理解

 我们得到一个由两个字符组成的字符串，`C`和`P`。 每个字符代表挂在墙上的一个物体。`C`意思是明信片，`P`意思是照片。 

Polycarpus 从左到右移除物体。 他不能跳过位置，并且在任何时候他只能携带一种类型的物体。 他也不能同时携带超过 5 个物体。 

任务是计算移除每个物品所需的最少前往衣柜的次数。 

重要的细节是，一旦对象类型发生变化，他必须清空双手才能继续。 例如，在序列中`CCCPP`，他可以将三张明信片一起携带，但当第一张照片出现时，他必须先参观衣柜。 

字符串长度最多为 100，这个长度很小。 即使是二次解也很容易通过。 尽管如此，问题的结构仍然允许直接线性扫描。 

一个常见的错误是放眼全球而非本地。 由于 Polycarpus 严格从左向右行走并且不能跳过项目，因此每个最大连续的相同字符块彼此独立。 

考虑这个例子：```
CCCCCC
```正确答案是`2`， 不是`6`。 他最多可以携带 5 件物品，因此 6 张明信片需要两次旅行。 

另一个容易犯的错误是忘记按类型更改进行拆分。```
CPPPP
```正确答案是`2`。 一张明信片的一次旅行，四张照片的一次旅行。 将整个字符串长度视为一批会错误地给出`1`。 

当块大小正好可以被 5 整除时，还存在一个差一的陷阱。```
CCCCCCCCCC
```正确答案是`2`， 不是`3`。 十件物品完全适合两次尺寸为 5 的旅行。使用如下公式`len // 5 + 1`如果不检查整除性，这里就会失败。 

## 方法

 蛮力的想法是从字面上模拟该过程。 我们遍历字符串，同时跟踪当前携带的类型以及当前手中有多少个对象。 每当类型发生变化或手中的物品达到 5 件时，我们就会前往衣柜并继续。 

由于字符串非常短，因此该模拟已经足够快了。 总功与弦长度成正比。 

有一种更简洁的方式来思考相同的过程。 

墙自然地分成最大连续的相同字符组。 例如：```
CCCPPCCCC
```变成：```
CCC | PP | CCCC
```每个组都是完全独立的，因为波利卡普斯不能在他手中混合类型。 一组尺寸内`k`，最小行程次数就是：```
ceil(k / 5)
```因为每次旅行最多可以携带 5 件物品。 

整个问题简化为扫描字符串，查找连续等字符块的长度，并对它们所需的行程求和。 

暴力模拟之所以有效，是因为它直接对真实过程进行建模，但分组观察将问题转化为简单的计数任务。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n) | O(1) | O(1) | 已接受 |
 | 最佳组计数 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取输入字符串。 
2. 初始化答案变量`ans = 0`。 
3. 从左到右扫描字符串，同时将连续的相等字符分组在一起。 
4. 对于每组，计算其长度`cnt`。 
5. 使用以下公式计算该组需要多少次行程：```
(cnt + 4) // 5
```这是整数算术`ceil(cnt / 5)`。 

1. 将此值添加到最终答案中。 
2. 继续，直到处理完整个字符串。 
3. 打印答案。 

为什么它有效：

 每个行程可能仅包含一种对象类型，因此来自不同组的对象永远不能组合到一个行程中。 在一个团体中，每次旅行携带尽可能多的物品始终是最佳选择，因为每次旅行的成本相同。 自愿携带少于 5 件物品只会增加出行次数。 由于每个组都是最优且独立处理的，因此总和是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()

n = len(s)
ans = 0
i = 0

while i < n:
    j = i

    while j < n and s[j] == s[i]:
        j += 1

    cnt = j - i
    ans += (cnt + 4) // 5

    i = j

print(ans)
```该解决方案使用两个指针，`i`和`j`，识别相同字符的连续块。`i`标记当前组的开始。`j`向前移动，直到角色发生变化。 组长度为`j - i`。 

表达式`(cnt + 4) // 5`是计算上限除以 5 的标准纯整数方法。它可以正确处理所有情况，包括组大小可以被 5 整除的情况。 

更新中`i = j`直接移动到下一个未处理的组。 

该实现避免了不必要的数组或额外的内存，因为组是动态处理的。

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    s = input().strip()

    n = len(s)
    ans = 0
    i = 0

    while i < n:
        j = i

        while j < n and s[j] == s[i]:
            j += 1

        cnt = j - i
        ans += (cnt + 4) // 5

        i = j

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("CPCPCPC\n") == "7\n", "sample 1"

# custom cases
assert run("C\n") == "1\n", "single item"
assert run("CCCCCCCCCC\n") == "2\n", "exact multiple of 5"
assert run("PPPPPP\n") == "2\n", "single group larger than 5"
assert run("CCCPPCCCC\n") == "3\n", "multiple groups"
assert run(("C" * 100) + "\n") == "20\n", "maximum length all same"
```| 测试输入| 预期产出 | 它验证了什么 |

 |`CCCCCCCCCC`|`2`| 精确整除 5 |

 ## 边缘情况

 考虑输入：```
CCCCCCCCCC
```该算法找到一组长度为 10 的组。```
(10 + 4) // 5 = 14 // 5 = 2
```所以答案是`2`。 这正确地处理了精确整除的情况。 

现在考虑：```
CPPPP
```这些团体是：```
C
PPPP
```第一个贡献`1`旅行，第二次贡献`1`行程，总共`2`。 

该算法从不尝试在类型更改中组合对象，这完全符合规则。 

最后，考虑高度交替的情况：```
PCPCPC
```每个组都有大小`1`，所以每个对象都需要自己的行程。 

该算法处理六个独立的组：```
1 + 1 + 1 + 1 + 1 + 1 = 6
```这证实分组逻辑也正确处理最大可能的碎片。
