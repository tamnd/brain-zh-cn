 ## 解决方案
 ## 问题理解

 每个历史事件由一个时间间隔表示`[a, b]`， 在哪里`a`是起始年份并且`b`是结束的一年。 如果一个事件开始较晚且结束较早，则该事件被视为包含在另一事件内。 正式地，事件`j`包含事件`i`什么时候：

-`a_j < a_i`-`b_i < b_j`任务是计算至少一个其他事件中包含多少个事件。 

输入最多可达`10^5`间隔。 比较每对事件的二次解大约需要`10^10`最坏情况下的比较，远远超出了 2 秒的限制。 这立即排除了任何`O(n^2)`方法。 我们周围需要一些东西`O(n log n)`，强烈建议排序。 

一个微妙的细节是，遏制同时取决于两个坐标。 只看开始年份或结束年份是不够的。 

考虑这个例子：```
3
1 10
2 5
6 9
```正确答案是：```
2
```两个都`[2,5]`和`[6,9]`在里面`[1,10]`。 

粗心的实现仅在排序后检查相邻间隔可能会错过其中一个间隔。 

另一个容易犯的错误是忘记了严格的不平等是必要的。 如果允许相同的端点，我们需要仔细区分严格遏制和非严格遏制。 这个问题避免了这种复杂性，因为所有开始和所有结束都是不同的，但算法仍然应该依赖于严格的正确排序。 

此示例演示了为什么跟踪迄今为止看到的最大结束年份有效：```
4
1 4
2 10
3 5
6 8
```正确答案是：```
1
```仅有的`[3,5]`被包含，因为它位于内部`[2,10]`。 

天真的“当前间隔早于上一个间隔结束”检查会错误地计数`[6,8]`，即使它的开始已经在外面`[2,10]`。 

## 方法

 蛮力方法很简单。 对于每个间隔`i`, 扫描所有其他区间`j`并检查是否：```
a_j < a_i and b_i < b_j
```如果存在这样的区间，则标记`i`如所包含的。 

这是有效的，因为可以在恒定时间内直接测试每对的定义。 问题在于规模。 和`10^5`间隔，比较次数变为：```
10^5 × 10^5 = 10^10
```这太慢了。 

关键的观察结果是，按起始年份排序后，遏制变得更加容易。 

假设我们通过增加对间隔进行排序`a`。 处理区间时`[a_i, b_i]`，排序顺序中每个较早的间隔已经具有较小的起始年份。 第一个遏制条件自动满足。 我们只需要知道任何较早的间隔是否具有较大的结束年份。 

这将问题转化为前缀最大查询。 

当我们从左到右扫描时，我们保持最大`b`到目前为止所看到的。 如果当前间隔有：```
b_i < max_b
```那么之前的某个区间会晚结束，并且由于排序也较早开始，因此包含当前区间。 

这将整个问题简化为一种排序加一次线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 将所有区间读入列表中。 

我们需要将所有间隔放在一起，因为解决方案取决于对它们进行全局排序。 
2. 按起始年份升序对间隔进行排序。 

排序后，每个较早的区间自动满足条件`a_j < a_i`。 
3. 初始化变量`max_b`具有非常小的值。 

这存储了所有先前处理的间隔中最大的结束年份。 
4. 从左到右扫描排序后的区间。 

对于每个间隔`[a, b]`，检查是否`b < max_b`。 
5. 如果`b < max_b`，增加答案。 

某些较早的间隔具有较大的结束年份，并且由于较早的间隔也较早开始，因此包含当前间隔。 
6. 更新`max_b = max(max_b, b)`。 

如果当前间隔具有迄今为止最大的结束年份，则未来间隔可能包含在当前间隔内。 
7. 打印最终计数。 

### 为什么它有效

 按起始年份排序后，当前间隔之前的每个处理间隔都具有严格较小的起始值。 遏制的唯一剩余要求是找到结束年份较大的较早间隔。 

变量`max_b`始终存储所有较早间隔中最大的结束年份。 如果当前间隔之前结束`max_b`，则存在一些较早开始较晚结束的区间，即包含当前区间。 

如果`b >= max_b`，那么没有比当前间隔晚结束的较早间隔，因此遏制是不可能的。 

由于在此不变量下每个区间都只处理一次，因此该算法会精确计算另一个区间内包含的区间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    intervals = []
    
    for _ in range(n):
        a, b = map(int, input().split())
        intervals.append((a, b))
    
    intervals.sort()
    
    max_b = -1
    ans = 0
    
    for a, b in intervals:
        if b < max_b:
            ans += 1
        
        max_b = max(max_b, b)
    
    print(ans)

solve()
```该解决方案首先读取所有间隔并按起始年份对它们进行排序。 Python 按字典顺序对元组进行排序，因此`intervals.sort()`自然地排序`a`。 

变量`max_b`跟踪已处理间隔中最大的结束年份。 最初它被设置为`-1`，它比任何有效的结束年份都安全地小。 

扫描期间，条件：```
if b < max_b:
```检测遏制。 因为间隔是按递增的开始顺序处理的，所以任何间隔都有助于`max_b`已经开始得更早了。 当当前间隔的结束年份较小时，恰好包含当前间隔。 

更新：```
max_b = max(max_b, b)
```必须在收容检查之后进行。 首先更新会使每个间隔与自身进行比较，这是不正确的。 

Python 整数处理的端点范围可达`10^9`安全无溢出问题。

 ## 边缘情况

 考虑尽可能最小的输入：```
1
1 2
```排序后，只有一个区间。`max_b`开始于`-1`， 所以`2 < -1`是假的。 答案依然存在`0`，这是正确的，因为不存在其他区间。 

现在考虑完全不相交的区间：```
4
1 2
3 4
5 6
7 8
```扫描过程如下：

 -`(1,2)`套`max_b = 2`-`(3,4)`有`4 < 2`， 错误的
-`(5,6)`有`6 < 4`， 错误的
-`(7,8)`有`8 < 6`, 假

 不计算间隔。 每个间隔都比之前的所有间隔结束得晚，因此遏制永远不会发生。 

最后，考虑一个区间包含许多不相关区间的情况：```
5
1 100
2 10
20 30
40 50
60 70
```排序顺序保持不变。 加工后`(1,100)`,`max_b = 100`。 每个较晚的间隔都有一个较小的结束年份，因此所有四个都被计算在内。 

这证实了算法背后的不变性。 一旦出现结束年份非常大的区间，则保证包含较早结束的每个较晚的区间，因为开始排序已通过排序处理。
