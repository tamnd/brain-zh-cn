 ## 解决方案
 ## 问题理解

 我们给出一个正整数数组和一个目标区间$[x, y]$。 我们可以从数组中删除两个不同的元素。 删除它们后，我们查看剩余的总和，我们希望剩余的总和落在给定的区间内。 

等价地，如果数组的总和是$S$，删除位置上的元素$i$和$j$留下总和$S - a_i - a_j$。 条件变为：$$x \le S - a_i - a_j \le y$$重新排列给出：$$S - y \le a_i + a_j \le S - x$$所以任务纯粹是关于计数对$(i, j)$其总和位于由总和确定的固定范围内。 

测试用例的输入大小很大，最多可达$2 \cdot 10^5$总元素。 任何$O(n^2)$每个测试用例方法将立即失败，因为即使$n = 2 \cdot 10^5$会暗示关于$2 \cdot 10^{10}$配对检查。 这推动我们走向$O(n \log n)$或者$O(n)$每个测试用例，通常使用两个指针排序或二分搜索。 

一个微妙的失败案例来自于正确处理转换后的边界。 由于我们将剩余总和的条件转换为对总和的条件，因此混淆时经常会发生错误$x, y$或者忘记重新计算每个测试用例的边界。 

具体的边缘情况是所有元素都相同并且有效范围非常严格。 例如，如果$a = [3, 3, 3]$,$x = 4$,$y = 4$，总和是 9，所以我们需要$5 \le a_i + a_j \le 5$，这是不可能的。 忘记正确减法的幼稚实现可能会错误地计算对。 

另一个极端情况是变换后边界变为负值或极大。 自从$a_i \ge 1$，总和始终为正，因此范围裁剪逻辑在没有特殊大小写的情况下仍必须正确运行。 

## 方法

 蛮力的想法很简单：尝试每一对$(i, j)$，计算删除后的剩余总和，并检查它是否位于$[x, y]$。 这是正确的，因为它直接遵循定义。 不过，需要检查$\frac{n(n-1)}{2}$每个测试用例成对，即使对于中等程度的情况也是不可行的$n$。 

关键的观察是删除两个元素仅取决于它们的总和，而不取决于它们的位置。 一旦我们重写条件$a_i + a_j$，问题就变成了一个经典的约束对和计数任务：计算有多少对位于一个值范围内。 

对数组进行排序后，我们可以用 sum 来计数对$\le R$在线性时间内使用两指针扫描。 通过计算两个界限的计数并相减，我们得到答案。 

蛮力之所以有效，是因为约束是每对局部的，但由于二次缩放而失败。 到对和范围的转换将问题简化为排序加上单调计数结构，从而启用两个指针。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了|
 | 排序+两个指针|$O(n \log n)$|$O(1)$额外 | 已接受 |

 ## 算法演练

 我们首先将问题转换为对和约束。 

1. 计算总和$S$数组的。 这是必要的，因为情况取决于移除后剩余的内容。 
2. 将剩余总和的条件转换为移除对总和的条件：$$L = S - y,\quad R = S - x$$任何有效对必须满足$L \le a_i + a_j \le R$。 
3. 对数组进行排序。 排序是必不可少的，因为它允许我们单调地推理对和。 
4. 计算有多少对有和$\le R$。 这是使用两指针技术完成的：一个指针从左侧开始，另一个指针从右侧开始，然后根据当前总和是否太大来缩小或扩展。 
5. 计算有多少对有和$< L$，或等效地用总和来计数对$\le L - 1$。 
6. 减法：有效对 = count($\le R$) − 计数($\le L - 1$）。 

两指针计数之所以有效，是因为对于固定的右指针，直到某个索引的所有左位置都形成有效对，因此我们可以批量累加计数，而不是单独检查。 

### 为什么它有效

 排序后，数组具有增加右索引只会增加对和的性质。 这种单调性确保对于每个固定$r$，有一个边界索引$l$这样所有的$i < l$满足$a_i + a_r \le X$。 这将创建一个连续的有效段，允许线性计数。 每对在所有正确的端点上都被精确计数一次，以保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_leq(a, bound):
    n = len(a)
    l, r = 0, n - 1
    res = 0
    while l < r:
        if a[l] + a[r] <= bound:
            res += r - l
            l += 1
        else:
            r -= 1
    return res

def solve():
    t = int(input())
    for _ in range(t):
        n, x, y = map(int, input().split())
        a = list(map(int, input().split()))
        s = sum(a)

        L = s - y
        R = s - x

        a.sort()

        ans = count_leq(a, R) - count_leq(a, L - 1)
        print(ans)

if __name__ == "__main__":
    solve()
```核心实现细节是辅助函数，用于对总和高于阈值的对进行计数。 它使用两端缩小的窗口。 当总和足够小时，之间的所有元素`l`和`r`配对`l`是有效的，所以我们添加`r - l`一步之遥。 

减法步骤至关重要。 我们计算一个包含范围$[L, R]$通过两个前缀样式计数的差异。 忘记了`L - 1`调整是差一误差的常见来源。

 ## 边缘情况

 一个关键的边缘情况是当变换后的边界变为负值时。 考虑：```
n=3, x=8, y=10
a=[3,2,1]
```这里$L=-4$,$R=-2$。 算法仍然正常运行，但每对和都是正数，因此两个计数函数都返回 0。这证实了不需要对无效范围进行特殊情况过滤。 

另一种情况是所有元素都相同时：```
n=5, x=1, y=1
a=[1,1,1,1,1]
```总和为 5，因此所需的对总和恰好为 4。每对贡献 2，因此没有一个符合条件。 两指针方法正确地计数为零，因为每个总和始终低于或高于界限，并且减法产生零而没有调整误差。 

最后一个微妙的情况是有效间隔非常宽，有效地允许所有对。 该算法计算所有$\frac{n(n-1)}{2}$配对通过$\le R$函数，并从下限减去零产生完整的组合计数，确认没有重复计数或丢失对。
