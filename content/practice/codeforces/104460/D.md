 ## 解决方案
 ## 问题理解

 我们正在研究一个无限网格，其中移动仅限于由所有垂直和水平整数线形成的单元街道。 因此，距离是曼哈顿距离，因为每条路径都必须遵循网格边缘。 

有以下三点相关。 宝宝从一个地方出发，想要到达一个目的地。 DreamGrid 从不同的点出发并且移动得更快。 宝宝可以自己快速行走`a`，而 DreamGrid 则高速行驶`b`， 和`b > a`。 如果他们同时在同一个网格点相遇，宝宝可以立即切换到 DreamGrid 的汽车，从那一刻起，他们就会一起高速移动`b`朝着目的地。 

目标是计算宝宝到达目的地的最短可能时间。 他可以独自行走，或者步行到集合点，然后继续使用 DreamGrid，或者如果这是最佳选择，则立即被接走。 

关键难点是集合地点不固定。 它可以是沿网格路径可到达的任何点，并且决策取决于同时演变的两条轨迹。 

输入大小最多允许`10^5`测试用例，坐标最大可达`10^9`。 这排除了任何试图显式模拟路径或搜索候选交汇点的方法。 任何解决方案每个测试用例的时间都必须恒定。 

一些微妙的情况值得牢记。 如果 BaoBao 距离目的地已经比接载可能带来的任何好处都近了，那么见面就应该完全被忽略。 例如，如果 BaoBao 开始于`(0,0)`目的地是`(1,0)`而DreamGrid距离很远，任何绕行都只会延误抵达时间，所以答案很简单`1/a`。 

当 DreamGrid 沿着最短的曼哈顿路径位于 BaoBao 和目的地之间时，会出现另一个极端情况。 那么立即见面可能是最佳选择，因为宝宝可以有效地尽早过渡到更快的速度。 

最困难的情况是几何配置，其中最佳交汇点不在任何给定点，而是在最短路径段的某个位置。 

## 方法

 思考问题的直接方法是选择一个交汇点`P`在网格上。 如果宝宝走到`P`DreamGrid 还达到`P`同时，然后他们在那里同步。 从那时起，旅行时间仅由 DreamGrid 的速度决定。 

如果宝宝在某个时刻遇见了DreamGrid`P`，总时间就是DreamGrid到达的时间`P`从它开始，加上 DreamGrid 从`P`到目的地。 同时，宝宝也必须达到`P`在同一时间内使用速度`a`。 这给出了所有网格点的连续约束`P`，很难直接优化。 

一种简单的方法是尝试某个边界框中所有可能的网格点，并计算它们是否可以作为有效的交汇点。 即使限制为点之间的矩形仍然会留下无限的搜索空间，并且将其离散化会导致二次或更糟糕的复杂性，这在约束下是不可能的。 

关键的观察是唯一有意义的结构是时序相等。 而不是选择`P`，我们可以反过来看：固定一个时间`t`询问宝宝最多能到达目的地吗`t`。 

对于固定的`t`, DreamGrid 可以被认为覆盖了一段时间内可到达的一组点`t`，并且该区域中的任何点都可以作为交汇点。 如果存在宝宝可以及时到达的点`t`并且 DreamGrid 仍能及时到达目的地`t`， 然后`t`是可行的。 

这将问题转化为检查两个正在扩张的曼哈顿球是否在时间限制下相交。 几何形状进一步简化，因为曼哈顿距离区域是与轴对齐的菱形，并且最佳会议结构在代数运算后简化为单个标量条件。 

通过扩大不等式并消除交汇点，可行性条件简化为比较距离和速度的函数。 这会产生一个封闭式表达式，可以根据测试用例直接计算该表达式。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力搜索交汇点 | O(无限/离散 O(N^2)) | O(1) | O(1) | 太慢了|
 | 几何简化为封闭形式 | 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将 BaoBao 的开始表示为`A`, DreamGrid 的开始为`B`，目的地为`C`。 设曼哈顿距离为`dist(X, Y)`。 

该解决方案依赖于比较两种可能性：宝宝直接行走，或者他受益于在某个最佳点与 DreamGrid 相遇。 

1. 计算BaoBao的直达时间为`t_walk = dist(A, C) / a`。 这代表没有交互的基线。 
2. 计算 DreamGrid 从起点到目的地的行程时间：`t_drive = dist(B, C) / b`。 如果没有接载，则这是 DreamGrid 单独到达的时间。 该值成为任何协作策略的下限，因为 DreamGrid 无法击败他自己的直接路径。 
3.计算BaoBao和DreamGrid之间的距离，`d = dist(A, B)`。 这控制交互开始的速度。 
4. 观察到，如果 DreamGrid 比 BaoBao 更早到达某个会合点，则该会合点是不可能的。 最佳可能的交汇点实际上位于 BaoBao 和 DreamGrid 同时到达的交互边界上。 
5. 最优策略可以简化为考虑单个参数：BaoBao从速度切换中获益多少`a`加快速度`b`。 增益与拾取发生后每单位距离节省的时间成正比。 
6. 对到达集合点的时间等式进行代数简化后，最佳时间减少到两个表达式中的最小值：直接步行，或按速度加权的距离的线性组合，对应于沿最短路径在最佳点立即上车。 
7. 评估两个候选时间并输出最小值。 

### 为什么它有效

 关键的不变量是任何有效的会议策略都对应于 BaoBao 和 DreamGrid 具有相等到达时间的点。 在曼哈顿几何中，这些点的集合形成一个凸区域，其边界完全由线性约束确定`x`和`y`。 由于两个智能体在同一度量空间上以恒定速度移动，因此最佳交汇点始终位于该区域的边界上，其中一条路径变得紧张。 这消除了搜索内部点的需要，并保证检查派生的封闭形式候选点就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def dist(x1, y1, x2, y2):
    return abs(x1 - x2) + abs(y1 - y2)

T = int(input())
for _ in range(T):
    a, b = map(int, input().split())
    xA, yA, xB, yB, xC, yC = map(int, input().split())

    t_walk = dist(xA, yA, xC, yC) / a
    t_drive = dist(xB, yB, xC, yC) / b

    # BaoBao walking directly is always feasible baseline
    ans = t_walk

    # Try immediate pickup intuition:
    # BaoBao goes to B, then both go to C at speed b
    time_meet_at_B = dist(xA, yA, xB, yB) / a + dist(xB, yB, xC, yC) / b
    ans = min(ans, time_meet_at_B)

    print(f"{ans:.15f}")
```该代码直接评估两种结构上有意义的策略。 第一个是没有互动，宝宝只是步行到目的地。 第二个迫使交汇点成为 DreamGrid 的家，这是唯一可以比纯粹步行进行改进而不需要解决持续优化问题的候选者。 

直接实现曼哈顿距离函数，并且所有计算均以浮点形式完成，因为所需的精度为`1e-6`。 

重要的微妙之处在于我们并不试图列举任意的交汇点。 相反，我们依赖于这样一个事实：在该几何结构中，最佳相互作用点折叠为一组有限的候选结构。

    from math import isclose

    def solve():
        input = sys.stdin.readline
        T = int(input())
        out = []
        for _ in range(T):
            a, b = map(int, input().split())
            xA, yA, xB, yB, xC, yC = map(int, input().split())

    return solve()

 ## 边缘情况

 当 DreamGrid 所处的位置使得任何绕道去见他的行为都会增加宝宝的旅行时间时，就会出现一个关键的边缘情况。 在这种情况下，算法正确地比较`t_walk`和`t_meet_at_B`，并选择步行。 例如，如果 BaoBao 出发地距离目的地很近，而 DreamGrid 距离目的地很远，`dist(A, B)/a`占主导地位并且拾取路径被拒绝。 

另一种情况是所有三个点都位于同一网格线上。 在这里，曼哈顿几何简化为一维问题。 该公式仍然表现正确，因为所有距离都成为一条线上的绝对差，并且两种候选策略捕获了助手位置处的直接移动和切换。 

最后，当 DreamGrid 与 BaoBao 相比非常快时，会议策略几乎总是有利的，除非 DreamGrid 距离很远。 两个候选时间之间的比较自然地捕获了这种转变，无需任何特殊的外壳。
