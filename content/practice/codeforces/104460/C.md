 ## 解决方案
 ## 问题理解

 我们得到一个仅由数字 0、6、8 和 9 组成的字符串。我们只执行一个操作：选择一个连续的段，将其反转，然后使用 180 度旋转规则替换该反转段中的每个数字，其中 0 映射到 0，8 映射到 8，6 和 9 相互交换。 

在所选段之外，字符串保持不变。 在段内，顺序被颠倒并且每个数字被变换。 

任务是计算通过选择任何非空段并应用此操作一次可以获得多少个不同的完整字符串。 

每个测试用例的字符串长度最多可达 10^6，总长度可达 10^7，这会立即排除子字符串的任何二次枚举。 任何解决方案对于每个测试用例都必须基本上是线性的，或者在最坏的情况下是线性的。 

一个微妙的点是，不同选择的片段可以产生相同的最终字符串。 这以两种方式发生。 首先，如果变换对段没有任何作用，这意味着段在反向和旋转操作下是不变的，那么所有这些段都会产生原始字符串。 其次，如果两个不同的段产生相同的修改后的字符串，我们将需要更改位置和未更改位置之间一致的重叠，这仅适用于此处的身份情况。 因此，唯一真正的重复来自于保持字符串不变的操作。 

一种简单的方法是枚举所有 O(n^2) 段，每次构造转换后的字符串，并将其插入到哈希集中。 这会立即失败，因为即使构建所有子字符串在这种规模下也太昂贵，并且每个转换在段长度上都是线性的。 

## 方法

 蛮力观点很简单。 对于每对 (l, r)，提取子字符串，反转它，应用数字旋转，然后将其写回到字符串的副本中。 每个结果都会被比较或散列。 这是正确的，但每个段的成本为 O(n)，在最坏的情况下导致总工作量为 O(n^3)，这是完全不可行的。 

关键的观察是我们实际上不需要构造最终字符串。 我们只需要了解两个操作何时产生相同的结果。 几乎所有部分都会产生独特的输出，除了那些不执行任何操作的部分。 

因此，问题归结为计算有多少段产生了不平凡的变化，并考虑到所有平凡的段都分解为一个结果，即原始字符串。 

如果反转和旋转片段产生完全相同的序列，则该片段不会被操作改变。 通过引入字符串的转换版本并将条件转换为对对齐索引的简单相等检查，可以更干净地重写该条件。 一旦重新制定，未改变的段就变成了两个对齐字符串完全匹配的间隔，这减少了对常量游程的计数。

 ## 算法演练

 我们为 180 度旋转下的数字定义一个辅助变换。 令 inv(x) 为 0→0, 8→8, 6↔9。 我们构建第二个字符串 u，其中 u[i] = inv(s[i])。 

我们还反转 u 得到 ur。 此步骤将段反转的效果与简单的前向比较结合起来。 

现在我们推理一个段 [l, r]。 运算后，该段变为reverse(inv(segment))。 当且仅当该段与原始字符串逐段匹配时，该段才保持不变。 

这导致了直接对齐条件：对于 [l, r] 中的每个索引 i，s[i] 必须等于 ur[i]。 因此，未更改的段正是完全包含在 s 和 ur 逐个字符相同的位置中的间隔。 

### 步骤

1. 通过对 s 的每个字符应用数字旋转来构造 u。 这捕获了 180 度的变换，但尚未反转。 
2. 将 ur 构造为 u 的倒数。 这会将转换后的位置与原始索引对齐，以便比较变得按索引进行。 
3. 构建一个数组 eq，其中如果 s[i] == ur[i]，则 eq[i] 为 true，否则为 false。 这标记了对称条件成立的位置。 
4. 扫描 eq 并将其分割为连续真值的最大连续段。 每个这样的段代表一个区域，其中完全位于其中的任何选定的 [l, r] 在操作后将保持不变。 
5. 对于长度为 L 的连续真值段，计算 L(L+1)/2 间隔。 对所有段求和即可得到未更改操作的数量。 
6. 令总子串为n(n+1)/2。 每个子串对应一个操作。 第 5 步中计数的所有子字符串都会生成原始字符串。 每个其他子字符串都会生成一个不同的转换字符串。 
7. 最终答案是total_substrings - 未更改的_substrings + 1。 

### 为什么它有效

 转换是确定性的，仅取决于所选的段。 如果某个段未更改，则它不会对最终字符串中的任何位置进行任何修改。 所有此类操作都会归结为相同的结果，即原始字符串。 任何至少改变一个位置的片段都会创建一种锚定到该片段的独特差异模式，并且不同的片段不能产生相同的完整字符串，除非两者都没有改变。 与 ur 相等的结构确保未更改的段在索引方面完全一致，因此对 eq 中的运行进行计数可以完全捕获所有冲突。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    inv = {'0': '0', '8': '8', '6': '9', '9': '6'}
    
    for _ in range(T):
        s = input().strip()
        n = len(s)

        u = ''.join(inv[c] for c in s)
        ur = u[::-1]

        eq = [0] * n
        for i in range(n):
            if s[i] == ur[i]:
                eq[i] = 1

        total = n * (n + 1) // 2

        good = 0
        i = 0
        while i < n:
            if eq[i]:
                j = i
                while j < n and eq[j]:
                    j += 1
                L = j - i
                good += L * (L + 1) // 2
                i = j
            else:
                i += 1

        print(total - good + 1)

if __name__ == "__main__":
    solve()
```该代码构造逆变换字符串及其反向字符串，以便段条件成为匹配索引处的简单相等检查。 这`eq`数组将问题压缩为查找连续的游程，并且对游程长度的算术取代了枚举子字符串的任何需要。 

这里的一个常见错误是试图直接使用 Manacher 算法将其视为回文计数问题。 这是不必要的，因为条件简化为固定对齐上的逐点相等，而不是中心扩展对称。

 ## 边缘情况

 关键的边缘情况是整个字符串在变换下保持不变。 例如808反转旋转后映射到自身。 在这种情况下，每个可能的段都会生成原始字符串，因此答案会折叠为 1。算法会检测到这一点，因为每个位置都满足 s[i] == ur[i]，从而生成单个全长游程。 

另一种边缘情况发生在根本没有位置匹配的情况下，例如 0689。这里 eq 仅包含零，因此不存在不变段。 每个子字符串都贡献一个不同的转换后的字符串，答案变为total_substrings + 1。算法自然地处理这个问题，因为好的总和为零。 

最后一个微妙的情况是交替匹配，例如 0 6 0 6 模式，其中 eq 分为多个运行。 每次运行都是独立处理的，并且它们的贡献不会干扰，因为子串在保持不变的同时不能跨越错误边界。
