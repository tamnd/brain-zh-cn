 ## 解决方案
 ## 问题理解

 我们正在观察一个循环时间系统，其中时间不是按照通常的 24 小时时钟运行，而是在未知的小时数后循环，称之为$k$。 在这个系统中，时间像往常一样提前一小时，只不过在达到$k-1$，它回绕到 0。因此状态空间实际上是算术模$k$。 

我们给定三个整数$x$,$y$， 和$z$。 解释是时钟显示$x$现在，在精确推进之后$y$小时，它显示$z$。 任务是确定一个有效值$k$使这种转变成为可能，或者报告说没有这样的转变$k$存在。 如果多个值$k$工作，任何一个都可以接受。 

关键的限制是两者$x$和$z$可以大到$10^9$， 和$y$也可以大到$10^9$，虽然可能最多有$10^5$测试用例。 这立即排除了任何尝试所有可能的方法$k$， 自从$k$本身可以达到$2 \cdot 10^9$，甚至每个测试用例进行线性扫描也是不可能的。 

一个微妙的点是包裹行为完全取决于模数$k$。 我们必须满足的方程不是简单的线性等式，而是模条件：$$(x + y) \bmod k = z.$$这引入了一个依赖项，其中$k$必须与两者的前向差一致$y$以及隐含的换行行为$x$和$z$。 

当根本没有发生换行时，就会出现边缘情况。 如果$x + y = z$在正常整数中，那么任何足够大的$k > \max(x, z)$有效，并且由于允许多个答案，因此这种情况总是可以解决的。 但是，这仅在以下情况下有效：$x + y \ge z$。 如果$x + y < z$，没有任何模块化包装可以产生更大的结果，所以答案一定是$-1$。 

另一个重要的边缘情况是当$y = 0$。 在这种情况下我们需要$x = z$。 如果不是，那立刻就不可能了。 如果是的话，那么任何$k > \max(x, z)$有效，但我们可以返回任何有效值。 

最重要的隐藏困难是$k$必须是“未包装”前向值与观察结果之间差异的除数，但仅在考虑了可能的包装之后。 这就是问题变得非同小可的原因。 

## 方法

 暴力方法会尝试所有可能的值$k$从$1$到$2 \cdot 10^9$。 对于每位候选人$k$，我们模拟这个过程：计算$(x + y) \bmod k$并检查它是否等于$z$。 根据问题的定义，这是正确的，但速度太慢。 高达$10^5$测试用例最多$2 \cdot 10^9$每个案例的候选人，这会导致难以管理$10^{14}$运营。 

关键的观察是我们实际使用的唯一信息$k$是它与价值观相互作用的方式$x$,$y$， 和$z$通过模运算。 如果我们重写条件：$$(x + y) \equiv z \pmod{k},$$这相当于：$$x + y - z \equiv 0 \pmod{k}.$$所以$k$必须是除数$d = x + y - z$，假设$d \ge 0$。 这立即将搜索空间从所有整数减少到$2 \cdot 10^9$仅限于单个数字的除数。 然而，我们仍然必须尊重模解释有效的约束，这意味着中间值不能超过$k-1$错误地。 

如果$d < 0$，那么该方程不能成立，因为模运算永远不会将值增加到超过$x + y$在包装之前，所以我们立即返回$-1$。 

一旦我们有$d \ge 0$，我们寻找一个有效的除数$k$的$d$这样$k > \max(x, z)$或者使得包裹结构保持一致。 由于任何有效$k$必须划分$d$，我们只需要检查除数$d$，最多有$O(\sqrt{d})$。 

这将问题转化为除数枚举问题与简单的一致性检查相结合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(T \cdot 2 \cdot 10^9)$|$O(1)$| 太慢了 |
 | 最优（差异除数）|$O(T \sqrt{d})$|$O(1)$| 已接受 |

 ## 算法演练

 1. 对于每个测试用例，计算$d = x + y - z$。 该量测量在应用模块化包装之前，幼稚的向前运动超出和低于目标状态的程度。 如果$d < 0$， 输出$-1$立即，因为没有模数可以将负超调转化为有效的环绕等式。 
2.如果$d = 0$， 然后$x + y = z$。 在这种情况下，任何足够大的$k$保持平等而不换行。 我们可以输出任何有效的$k$， 例如$k = 2 \cdot 10^9$，因为它总是满足约束条件。 
3.如果$d > 0$, 枚举所有除数$d$。 对于每个除数$k$，检查是否满足时钟约束。 除数很重要的原因是$k$必须除以原始前向时间和观察到的回绕时间之间的差，否则模等式无法成立。 
4. 对于每个候选除数$k$，验证是否从$x$转发通过$y$模下$k$产量$z$。 即使存在多个除数，这种直接检查也能确保正确性。 
5.返回第一个有效的$k$成立。 如果不存在则输出$-1$。 

### 为什么它有效

 核心不变量是任何有效的时钟大小$k$迫使差异$x + y - z$恰好是$k$。 这是模等价的直接结果。 相反，任何也遵循环绕行为的除数都会正确地重建相同的模循环。 由于我们枚举了约束系统的唯一数字的所有可能约数，因此我们不会错过任何有效的候选者，也不会接受无效的候选者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        x, y, z = map(int, input().split())

        d = x + y - z

        if d < 0:
            print(-1)
            continue

        if d == 0:
            print(2_000_000_000)
            continue

        # enumerate divisors of d
        ans = -1
        i = 1
        while i * i <= d:
            if d % i == 0:
                k1 = i
                k2 = d // i

                # candidate k1
                if k1 >= 1 and k1 <= 2_000_000_000:
                    if (x + y) % k1 == z:
                        ans = k1
                        break

                # candidate k2
                if k2 >= 1 and k2 <= 2_000_000_000:
                    if (x + y) % k2 == z:
                        ans = k2
                        break

            i += 1

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案直接遵循简化为除数搜索。 价值$d = x + y - z$捕获由模运算引起的唯一结构约束。 除数枚举循环运行至$\sqrt{d}$，这已经足够了，因为每个有效模数都必须以除数对的形式出现。 

一个微妙的实现细节是处理两者$i$和$d/i$对称，因为有效$k$可以出现在除数对的任一侧。 早点休息是安全的，因为任何有效的$k$可以接受，第一个找到的立即返回。 

特殊情况$d = 0$避免了不必要的除数逻辑，并反映了实际上没有强制执行包装约束的事实。

x = 1, y = 9, z = 1
```这里：$$d = 1 + 9 - 1 = 9$$我们列举 9 的约数：1、3、9。 

| 步骤| 我| d % 我 | k 候选人 | 检查 (x+y)%k | 有效|
 | ---| ---| ---| ---| ---| ---|
 | 1 | 1 | 0 | 1, 9 | 10% 1 = 0, 10% 9 = 1 | 1 或 9 |

 1和9在原始算术中都是有效的，但只有符合约束条件的才是可接受的。 由于首先找到该算法，该算法立即返回 1。 

这表明可以存在多个有效时钟。 

### 示例 2

 输入：```
x = 3, y = 49, z = 4
```计算：$$d = 3 + 49 - 4 = 48$$约数包括 1、2、3、4、6、8、12、16、24、48。 

| 步骤| 我| d % 我 | k 测试 | (x+y)%k | 匹配 z=4 |
 | ---| ---| ---| ---| ---| ---|
 | 1 | 1 | 0 | 1, 48 | 0, 0 | 没有|
 | 2 | 2 | 0 | 2、24 | 0, 0 | 没有|
 | 3 | 3 | 0 | 3, 16 | 0, 0 | 没有|
 | 4 | 4 | 0 | 4, 12 | 0, 10 | k=4 匹配 |

 在$k = 4$，我们得到：$$(3 + 49) \bmod 4 = 52 \bmod 4 = 0 \neq 4$$因此，尽管它是一个除数，但它未能通过最终检查，我们继续直到有效的匹配或耗尽。 

这说明了为什么除了除数逻辑之外还需要最终的模块化验证。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(T \sqrt{d})$| 每个测试枚举除数最多$\sqrt{d}$，并且在恒定时间内检查每个候选者 |
 | 空间|$O(1)$| 每个测试用例仅存储几个整数 |

 边界舒适，因为$T \le 10^5$，甚至对于大的$d$，由于平方根限制，除数枚举在实践中是有效的。

 ## 边缘情况

 一种边缘情况是当$x + y < z$。 例如，$x=2, y=1, z=10$。 然后$d = -7$，算法立即输出$-1$。 任何模块化系统都无法将值增加到超出包装之前的线性总和，因此没有$k$可以满足条件。 

另一个边缘情况是当$x = z$和$y = 0$。 例如，$x=5, y=0, z=5$。 然后$d=0$，算法输出一个大的有效值$k$， 例如$2 \cdot 10^9$。 这是有效的，因为没有时间流逝，所以任何足够大的周期都保持平等。 

最后一个微妙的情况是存在多个除数但只有其中一些满足模条件。 为了$x=3, y=49, z=4$，我们看到了几个因数$48$存在，但只有一个子集实际上产生正确的模块化结果。 该算法显式检查每个候选者，而不是假设所有除数都有效，从而确保这些混合情况下的正确性。
