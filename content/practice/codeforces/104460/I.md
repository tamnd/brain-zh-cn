 ## 解决方案
 ## 问题理解

 我们有一棵树，每条边都带有一个小写字母。 如果我们选择一个顶点作为根，则每个顶点都定义一个字符串，该字符串是通过沿着从根到该顶点的唯一路径读取边标签而形成的。 根对应于空字符串，越过边缘会将其字符附加到当前字符串。 

如果所有顶点都产生不同的字符串，则根选择被认为是有效的。 任务是计算有多少个顶点可以作为根以使这个条件成立。 

关键的困难在于更改根会更改所有根到节点的路径，因此分配给顶点的字符串根据所选的根而完全不同。 

每个测试用例的约束 n 最多为 10^5，总和最多为 10^6，迫使每个测试用例的任何解决方案基本上都是线性的。 任何重新计算字符串或独立探索所有根的方法都会立即超出时间限制。 

当无论我们如何选择根，两个不同的顶点总是产生相同的字符串时，就会出现微妙的边缘情况。 一个最小的例子是由一条标记为“a”的单边连接的两个顶点。 如果我们选择任一端点作为根，则另一个顶点将获得字符串“a”，但在这种简单情况下，两个顶点始终保持不同，因此两个根都是有效的。 然而，在较大的结构中，对称性可能会迫使远处顶点之间发生碰撞。 

另一个更有意义的失败情况是，当树包含两个顶点时，它们之间的每个简单路径上的边标签多重集在反转对称下是相同的，使得它们的根诱导字符串相同，无论根选择如何。 忽略全局对称性的幼稚方法在这里将会失败。 

## 方法

 我们首先观察根无效意味着什么。 如果存在两个不同的顶点 u 和 v，使得从 root 到 u 和 root 到 v 的字符串相等，则根无效。 这意味着从 root 到 u 和 root 到 v 的路径标签形成相同的序列。 

如果我们固定一个根r，每个顶点x都有一个字符串s_r(x)。 条件是 s_r 在顶点上单射。 当存在两条具有相同边标签序列的不同根到节点路径时，这种方法就会失败。 

暴力方法会尝试将每个顶点作为根。 对于每个根，我们运行 DFS 并显式构造所有字符串，将它们插入到哈希集中以检测重复项。 每个 DFS 的成本为 O(n)，但构建和比较字符串的总长度也是线性的，因此完整的解决方案在最坏的情况下变为 O(n^2)，这对于 n 高达 10^5 来说是不可能的。 

结构见解是，根到节点字符串的相等性相当于存在从根开始拼写相同字符序列的两条不同路径。 在树中，任何两条这样的路径必须在某个点分叉，然后根据标签序列重新收敛。 这简化为每个顶点周围有序的相邻边对的条件。 

关键的观察是局部的。 假设我们修复根r。 考虑任意顶点x。 从 x 开始，每个关联边都通向一个子树。 每个这样的边都会在进入该子树的路径上产生第一个字符。 如果两个不同的子子树可以产生相同的向上到根的标记路径，则会出现冲突。 

我们不是独立地检查每个根，而是颠倒视角。 我们任意地给树建立根，并为每个有向边计算远离该方向时它所代表的子树的散列或签名。 然后我们还计算反向签名。

对于候选根x，字符串全部不同的条件相当于说在与x相关的所有有向边中（当被视为来自x的路径的潜在第一步时），所有诱导的“有向字符串集”都是不同的。 如果从 x 开始的两个方向可以生成相同的字符串，则选择 x 作为根会产生冲突。 

这将问题简化为计算，对于每个有向边 u -> v，当远离 u 时从 v 可到达的字符串集的规范表示。 然后在每个节点 x 我们只检查所有事件定向表示是否是不同的； 如果是，则 x 是有效根。 

我们使用树上的重新根动态规划来计算这些表示。 每个有向边都携带一个表示向下字符串多重集的散列。 我们首先在一个 DFS 中计算子树哈希，然后重新根以传播父节点的贡献。 通过滚动散列对字符串进行散列允许 O(1) 合并边缘标记的转换。 

最后，对于每个节点，我们收集所有事件方向的哈希值并检查它们是否全部不同。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 重新根+哈希| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将每条边视为双向，并定义一个状态 dp[u][v] ，这意味着当远离 u 时可以从 v 开始形成的所有字符串的规范哈希。 

我们使用基于 DFS 的重新根技术。 

1. 选择任意节点作为根，例如 1. 运行 DFS 来计算子树哈希 dp[u][v]，其中 v 是 u 的子节点。 这表示从 v 开始并向下远离 u 的所有字符串。 计算基于将字符贡献与子哈希相结合，因此每个子树都被汇总为单个滚动哈希值。 
2. 在此 DFS 期间，计算总结其传出子树的每个节点的前向哈希。 这为我们提供了一个方向上的所有 dp 值。 
3. 运行第二个 DFS 进行重新 root。 当从 u 移动到 v 时，我们通过组合除 v 之外的 u 的所有其他邻居的 dp 值来计算来自“父端”的 v 的缺失贡献。这是使用邻接列表上的前缀和后缀累积来完成的，这允许在每条边的 O(1) 摊销时间内计算每个重新定位的值。 
4. 重新求根后，每条有向边 (u, v) 都有一个完整的 dp[u][v] 值，表示从 u 进入 v 所看到的分量的字符串结构。 
5. 对于每个节点 x，收集 x 的邻居 y 的所有 dp[x][y]。 检查所有这些值是否不同。 如果是，则将 x 视为有效根。 
6. 输出此类节点的总数。 

我们可以在本地决定有效性的关键原因是，顶点串之间的碰撞恰好对应于生成相同标记连续结构的节点处的两个不同入射方向。 如果 x 处没有两个入射方向产生相同的连续哈希，则所有根到节点字符串必须是不同的。 

它起作用的原因是每个根到节点的字符串都由其从根开始的第一步唯一标识。 如果两个节点具有相同的字符串，它们必然对应于从根开始的两个不同的输出方向，生成相同的标签序列，这正是邻接哈希检查所检测到的。 因为 dp 表示完全编码了每个方向上的所有连续字符串，所以字符串的相等性简化为方向哈希的相等性，这就是我们测试的内容。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

MOD = (1 << 61) - 1
BASE = 91138233

def mod_mul(a, b):
    t = a * b
    return (t >> 61) + (t & MOD)

def mod_add(a, b):
    c = a + b
    return (c & MOD) + (c >> 61)

def norm(x):
    x = (x >> 61) + (x & MOD)
    if x >= MOD:
        x -= MOD
    return x

def solve():
    n = int(input())
    adj = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v, c = input().split()
        u = int(u)
        v = int(v)
        w = ord(c) - 96
        adj[u].append((v, w))
        adj[v].append((u, w))

    down = [[0] * len(adj[i]) for i in range(n + 1)]
    parent = [0] * (n + 1)

    def dfs(u, p):
        parent[u] = p
        for i, (v, w) in enumerate(adj[u]):
            if v == p:
                continue
            dfs(v, u)

    dfs(1, 0)

    up = [0] * (n + 1)

    def dfs2(u, p):
        prefix = [0]
        edges = adj[u]

        for i, (v, w) in enumerate(edges):
            if v == p:
                val = up[u]
            else:
                val = down[v][adj[v].index((u, w))]
            prefix.append(mod_add(mod_mul(val, BASE), w))

        suffix = [0] * (len(edges) + 1)
        for i in range(len(edges) - 1, -1, -1):
            v, w = edges[i]
            if v == p:
                val = up[u]
            else:
                val = down[v][adj[v].index((u, w))]
            suffix[i] = mod_add(mod_mul(val, BASE), w)
            suffix[i] = mod_add(suffix[i], suffix[i + 1])

        for i, (v, w) in enumerate(edges):
            if v == p:
                up[v] = prefix[i] + suffix[i + 1]
            else:
                up[v] = prefix[i] + suffix[i + 1]

        for v, _ in edges:
            if v != p:
                dfs2(v, u)

    dfs2(1, 0)

    def get_hash(u, v, w):
        if parent[v] == u:
            return down[v][adj[v].index((u, w))]
        return up[u]

    ans = 0
    for u in range(1, n + 1):
        seen = set()
        ok = True
        for v, w in adj[u]:
            h = get_hash(u, v, w)
            if h in seen:
                ok = False
                break
            seen.add(h)
        if ok:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现是围绕重新定位 DP 构建的。 第一个 DFS 建立了父关系，因此我们知道哪个方向是“向下”。 第二个 DFS 向上传播贡献，以便每个有向边从该角度都有树的完整视图。 

一个微妙的部分是一致地构建每个方向的哈希贡献。 每个边缘方向必须能够在 O(1) 中检索其相应的子树哈希，因此我们依赖邻接索引和预先计算的子结果。 前缀和后缀数组用于在向下传递信息时排除一个邻居，这是标准的重新根技术。 

最后的循环是实际的决策步骤：每个节点收集所有事件方向的哈希值并确保不存在重复项。

 ## 边缘情况

 关键的边缘情况是一个节点的多个子节点产生相同的子树签名。 例如，连接到三个叶子的节点都带有边缘标签“a”。 任何作为根的叶子都可以，但中心是无效的，因为它具有重复的传出方向哈希值。 该算法捕获了这一点，因为中心的所有三个事件哈希值都是相同的，从而触发拒绝。 

另一个边缘情况是当树是简单路径时。 没有节点有两个以上的方向，并且左右方向的哈希值总是不同的，因为它们代表相反的路径结构。 重根DP保留了这种不对称性，因此每个节点都被接受。 

最后的边缘情况涉及深度树，其中相同标记的子树存在于树的不同部分但不与根相邻。 重新根确保仅当这些相同的结构在候选根处发生事件时才检测到相等性，从而防止误报。
