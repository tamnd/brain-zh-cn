 ## 解决方案
 ## 问题理解

 我们得到一个无向加权图，其中每个顶点代表城市中的一个位置，每条边代表一条具有行程时间的双向道路。 BaoBao 从节点 1 开始，想要到达一组退出节点中的任何一个。 

复杂的是，每次宝宝到达一个节点时，当他站在那里时，该节点上最多一定数量的事件边可能会暂时无法使用。 具体来说，如果节点i的值为di，那么在BaoBao进入i后，对手最多可以选择与i相关的di条边并阻止它们。 一旦BaoBao离开i，所有那些被阻挡的边就会再次变得可用，并且对手下次进入i时可能会选择不同的集合。 宝宝不知道哪些边会被阻塞，所以他每次到达一个节点时都必须计划最坏的选择。 

问题是确定 BaoBao 是否可以保证到达任意出口，如果可以，则计算最坏情况下可能的最小行程时间。 

重要的解释是，这是依赖于节点访问的对抗性边缘删除下的最短路径问题。 每当访问每个节点时，对手就可以动态地从每个节点中删除最多 di 个边，我们必须计算最佳保证策略。 

限制很大：每个测试用例最多 100,000 个节点，总共最多 300 万条边。 这排除了任何重复重新计算最短路径或模拟对抗性选择的解决方案。 任何将图形状态视为每次访问都会以显式方式更改的方法都会立即变得太慢。 

当节点的 di 等于其度数时，就会出现微妙的边缘情况。 在这种情况下，每当 BaoBao 到达时，所有传出边缘都会被阻塞，这意味着该节点在最坏的情况下可能会像死胡同一样。 如果该节点不是出口，则即使它在图中已连接，它也可能变得实际上不可到达。 

## 方法

 直接尝试是从节点 1 运行 Dijkstra，每次遍历一条边时都将其视为所有边始终可用。 这完全忽略了对手，并且是不正确的，因为找到的最短路径可能依赖于可以在需要时准确阻挡的边缘。 

更忠实的蛮力会尝试模拟对手。 在每次节点访问时，我们都会考虑可能被阻塞的大小为 di 的关联边的所有子集，并计算这些删除下的最短路径。 由于每个节点引入了可能的阻塞边集的二项式数量，并且这些选择在整个路径上相互作用，所以这种组合很快就会爆炸。 即使是度数为 20 且 di = 10 的单个节点也会产生数千个状态，并且在一条路径上，图大小会呈指数增长。 

关键的见解是将对手重新解释为不是随着时间的推移动态选择边缘，而是作为节点可以提供多少“流量”或“冗余”的约束。 当BaoBao到达一个节点时，最多可以删除di条边，因此实际上只有最小的输出选项是可靠的。 这表明我们应该感兴趣的是通过一个节点存在多少条不相交的“备份”路由，以及被迫避开最佳 di 边的成本有多大。 

正确的简化是将每个节点转换为一个结构，该结构考虑了最多 di 条边在入口处不可用的可能性。 对于每个节点，我们按权重对其关联边进行排序，并观察到在最坏的情况下，对手总是会删除最便宜的有用转换，以迫使 BaoBao 采取更昂贵的替代方案。 这导致了修改后的松弛规则：当我们位于一个节点时，我们不能依赖 di 最小的传出边，因此转换必须基于第 (di + 1) 个最佳可用选择。

这将问题转换为修改后的最短路径，其中每个节点在任何决策中都有效地抑制其最有吸引力的传出边，迫使我们考虑替代边。 我们可以通过为每个节点预先计算一个过滤的邻接列表来实现这一点，其中只有超出每个节点最小的边可用于有保证的遍历决策。 然后我们在这个修剪后的结构上运行标准 Dijkstra。 

微妙之处在于，修剪对于每个边缘端点来说不是对称的； 一条边可能可以从一个端点使用，但不能从另一端点使用，具体取决于 di 值。 因此每个方向都必须独立验证。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(米) | 太慢了 |
 | 度修剪 Dijkstra | O(m log n) | O(米) | 已接受 |

 ## 算法演练

 1. 对于每个节点，收集所有关联边并按权重排序。 这使我们能够推断出对手更愿意阻止哪些边缘。 
2.对于每个节点i，将其最小权重入射边标记为在最坏情况条件下可能可阻塞。 这些是 BaoBao 在 i 处做出决策时不能可靠依赖的边。 
3.通过为每个节点仅保留不在其最小关联边中的那些边来构建过滤邻接结构。 每个剩余的边都被认为可以从该端点安全使用。 
4. 由于边是无向的，因此对两个端点独立地重复过滤。 如果至少一个端点允许在其局部约束下遍历一条边，则该边在最终图中可用。 这捕获了如果存在对手无法同时使其无效的方向，则 BaoBao 可以遍历。 
5. 从节点 1 开始在此过滤图上运行 Dijkstra，计算到所有节点的最短距离。 
6. 在所有出口节点中，取最小距离。 如果无法到达出口，则输出-1。 

我们可以简化为静态图的关键原因是对手的选择仅取决于当前节点，并且不会在访问期间累积。 每个到达都是独立的，因此最坏情况的边缘抑制可以被视为每个节点的过滤规则而不是依赖于历史的过程。 

### 为什么它有效

 对手在节点 i 的能力仅限于在到达时刻删除最多 di 个事件边。 这意味着任何依赖于该节点上最便宜的事件选项的边的策略都可以在单次访问中失效。 因此，任何有保证的路径都必须避免依赖这些边作为必要的转换。 剩下的就是当宝宝被迫前进时，无法同时压制的边缘。 因为这个约束是本地的，并且在每次访问后都会重置，所以一旦我们删除所有本地不安全的选择，可达结构就变成静态的。 然后，标准最短路径正确性适用于该简化图。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    T = int(input())
    for _ in range(T):
        n, m, k = map(int, input().split())
        exits = list(map(int, input().split()))
        d = list(map(int, input().split()))

        adj = [[] for _ in range(n + 1)]
        edges = []

        for i in range(m):
            x, y, w = map(int, input().split())
            adj[x].append((w, y, i))
            adj[y].append((w, x, i))
            edges.append((x, y, w))

        allowed = [set() for _ in range(n + 1)]

        for u in range(1, n + 1):
            if not adj[u]:
                continue
            adj[u].sort()
            limit = d[u - 1]
            for idx, (w, v, eid) in enumerate(adj[u]):
                if idx >= limit:
                    allowed[u].add(eid)

        graph = [[] for _ in range(n + 1)]
        for eid, (x, y, w) in enumerate(edges):
            if eid in allowed[x] or eid in allowed[y]:
                graph[x].append((y, w))
                graph[y].append((x, w))

        INF = 10**30
        dist = [INF] * (n + 1)
        dist[1] = 0
        pq = [(0, 1)]

        while pq:
            du, u = heapq.heappop(pq)
            if du != dist[u]:
                continue
            for v, w in graph[u]:
                nd = du + w
                if nd < dist[v]:
                    dist[v] = nd
                    heapq.heappush(pq, (nd, v))

        ans = min((dist[e] for e in exits), default=INF)
        print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```该实现首先使用边缘标识符构建邻接列表，以便我们可以应用特定于节点的过滤。 对于每个节点，边按权重排序，最小的 di 被从其可用集中删除。 这是每个节点独立完成的，因为对手在每次到达时都在本地进行操作。 

第二阶段构建一个简化图，其中如果一条边可从至少一个端点使用，则保留一条边。 这很关键，因为如果存在边缘未被局部约束完全抑制的方向，则遍历是可能的。 

最后，标准 Dijkstra 计算最短距离。 答案是所有出口节点之间的最小距离。 

一个微妙的实现细节是索引：节点值 di 按照输入顺序从 1 开始，因此我们访问 d[u - 1]。 另一个关键点是，我们不需要两个端点都允许有一条边，而只需要至少一条，因为移动是无向的，并且可行性取决于有效的遍历方向。 

## 工作示例

 考虑一个小图，其中节点 1 连接到节点 2 和节点 3，并且 2 和 3 都通向出口节点 4。假设节点 2 的 di 较小，因此删除了其最便宜的边，从而强制采用更长的路线，而节点 3 允许直接移动。 

| 步骤| 当前节点 | 距离 | 可用的动作|
 | ---| ---| ---| ---|
 | 1 | 1 | 0 | 1→2, 1→3 |
 | 2 | 2 | 2 | 只有昂贵的边缘才能幸免于过滤|
 | 3 | 3 | 1 | 直接安全路径|
 | 4 | 4 | 2 | 已到达出口 |

 此跟踪显示了节点 2 处的修剪如何删除看起来最优的过渡并强制使用更长的路径通过节点 3。 

现在考虑一种情况，所有节点的 di 都等于度数，因此每个节点在到达时都会阻塞所有传出边。 在这种情况下，没有任何边能够幸免于来自任一端点的过滤，并且简化图根本没有边。 

| 节点| d_i | 学位| 幸存的边缘|
 | ---| ---| ---| ---|
 | 1 | 2 | 2 | 无 |
 | 2 | 1 | 1 | 无 |
 | 3 | 0 | 1 | 无 |

 从节点 1 启动 Dijkstra 无法到达任何出口，因此输出为 -1。 这证实了模型正确捕获了总阻塞场景。

 ## 边缘情况

 当起始节点本身具有相对于其度数较大的 di 时，就会出现临界边缘情况。 在这种情况下，来自节点 1 的大多数传出边可能会在过滤阶段被删除。 该算法仍然可以正确处理这个问题，因为 Dijkstra 只是从剩余的安全边开始，如果没有剩余，到所有其他节点的距离将保持无限。 

当出口节点只能通过完全抑制其传出边缘的节点到达时，会出现另一种边缘情况。 在这种情况下，这些节点在简化图中成为死胡同，Dijkstra 自然无法通过它们传播，产生 -1。 这与“宝宝”不能依靠通过严格控制区域的强制过渡的解释相吻合。
