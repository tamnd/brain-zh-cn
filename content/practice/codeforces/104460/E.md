 ## 解决方案
 ## 问题理解

 我们得到一个表示一行灯的二进制数组，其中每个位置要么打开，要么关闭。 我们可以执行选择起始索引并翻转固定长度的连续段的操作$L$。 每个操作总是使用相同的$L$，我们最多可以申请$k$此类操作。 目标是确定最小可能的段长度$L$这样所有最初打开的灯都可以在允许的操作次数内关闭。 

关键在于每个操作在长度上不自适应，仅在位置上自适应。 一次$L$是固定的，唯一的自由是在哪里放置窗口，我们想知道是否最多可以覆盖字符串中的所有内容$k$该长度的间隔。 

约束足够大，任何对所有选择的二次模拟$L$并且所有的安置都是不可行的。 自从$n$可以达到$2 \times 10^5$每个测试用例的总和达到$2 \times 10^6$，我们必须以每个测试用例大致线性或接近线性为目标。 这排除了任何尝试模拟每个候选人操作的方法$L$以一种天真的方式。 

一个微妙的点是，除了覆盖范围之外，重叠并不重要。 我们永远不需要在操作过程中对精确的开关状态进行建模； 仅包含最多包含“1”的所有位置$k$间隔。 

当实现尝试贪婪放置而没有正确跟踪先前操作已经覆盖的距离时，会出现常见的失败情况。 

例如，考虑：```
n = 5, k = 1
s = 10001
```如果$L = 3$，一个天真的贪婪者可能会将间隔从 1 开始放置以覆盖第一个 1，但它会错过最后一个。 无论如何，正确的放置都会失败，因为一个间隔无法覆盖长度超过 3 的两个分离区域。任何不精确推理覆盖限制的方法都会错误地评估可行性。 

## 方法

 蛮力的想法很简单。 对于固定的$L$，我们从左到右扫描字符串。 每当我们遇到尚未覆盖的“1”时，我们都会从该位置开始进行操作并覆盖下一个$L$细胞。 我们重复直到所有的都被覆盖或者超过$k$运营。 这是正确的，因为尽早设置间隔永远不会降低未来的灵活性。 

问题是检查一个$L$需要$O(n)$，并尝试所有$L$值从 1 到$n$导致$O(n^2)$，对于$n = 2 \times 10^5$。 

关键的观察是可行性是单调的$L$。 如果某个$L$最多足以覆盖所有$k$操作，然后任何更大的$L$也足够了，因为每个操作覆盖更多单元并且永远不会增加所需的操作数量。 这使我们能够对答案进行二分搜索。 

现在问题减少到检查固定的可行性$L$，这可以在线性时间内贪婪地完成。 我们扫描字符串，每当我们发现未覆盖的“1”时，我们就从该位置开始放置一个间隔并向前跳$L$。 使用的间隔数与$k$。 

贪婪可行性检查和二分搜索的结合产生了有效的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 通过贪婪检查对 L 进行暴力破解 |$O(n^2)$|$O(1)$| 太慢了|
 | 二分查找+贪心检查|$O(n \log n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们使用二分搜索独立解决每个测试用例$L$。 

1. 定义一个函数`can(L)`检查是否可以使用最多覆盖所有“1”位置$k$长度段$L$。 我们从左到右进行模拟，跟踪最后放置的段到达的距离。 
2. 内部`can(L)`，我们维护一个指针`i`扫描字符串和计数器`cnt`我们使用了多少段。 当我们遇到一个位置时`i`对于尚未覆盖的“1”，我们递增`cnt`并将覆盖范围设置为从`i`到`i + L - 1`。 
3. 然后，我们通过移动来跳过该段覆盖的所有位置`i`向前。 这确保了每个段都被贪婪地放置在最早可能的未覆盖“1”处，从而最大限度地减少浪费的覆盖范围。 
4. 如果在任何时候`cnt > k`，我们提前停止并返回 false，因为我们已经超出了允许的操作次数。 
5. 执行二分查找$L$从 1 到$n$。 对于每个中点，调用`can(mid)`。 如果可行，我们尝试较小的值； 否则，我们增加$L$。 
6.输出最小的$L$为此`can(L)`返回真。 

贪婪放置对于固定的情况是最佳的$L$因为将一个段放置在第一个未覆盖的“1”之后并不能减少所需的段数，并且可能只会留下额外的未覆盖的段。 

### 为什么它有效

 正确性取决于覆盖不变量。 在每个放置的段之后，直到其右端点的所有位置都被完全解析，这意味着未来的决策不依赖于它们。 每个未覆盖的“1”都会强制至少有一个段必须在该位置或之前开始。 贪婪策略总是尽早满足这一要求，确保没有片段浪费在已经覆盖的区域上。 因此，所产生的段数是最小的$L$，使可行性检查更加准确。 

因为可行性是单调的$L$，二分查找$L$有效，并且该组合产生全局最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(s, n, k, L):
    cnt = 0
    i = 0
    while i < n:
        if s[i] == '1':
            cnt += 1
            if cnt > k:
                return False
            i += L
        else:
            i += 1
    return True

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    lo, hi = 1, n
    ans = n

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(s, n, k, mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```功能`can`是贪婪覆盖过程的直接实现。 关键细节是，当我们点击“1”时，我们立即执行一项操作并向前跳转$L$，因为任何最佳解决方案都必须以一定的间隔覆盖该位置，而延迟只会带来以后额外操作的风险。 

二分搜索以标准方式实现，缩小可行区域，直到最小有效区域$L$被发现。 

## 工作示例

 考虑输入：```
n = 5, k = 2
s = 10101
```我们评估可行性$L = 2$。 

| 我| s[i] | 行动| 碳纳米管| 下一个我 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 放置间隔 [0,1] | 1 | 2 |
 | 2 | 1 | 放置间隔 [2,3] | 2 | 4 |
 | 4 | 1 | 放置间隔 [4,5] | 3 | 停止|

 我们使用了 3 次操作，超过了$k=2$， 所以$L=2$是不可行的。 

现在考虑$L = 3$。 

| 我| s[i] | 行动| 碳纳米管| 下一个我 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 地点 [0,2] | 1 | 3 |
 | 3 | 0 | 跳过| 1 | 4 |
 | 4 | 1 | 地点 [4,6] | 2 | 7 |

 这里我们正好使用了 2 个操作，所以$L=3$是可行的。 

这表明如何增加$L$减少了所需段的数量并表现出单调性。

 ## 边缘情况

 一种边缘情况是所有“1”都聚集在一起。 例如：```
n = 6, k = 1
s = 011110
```为了$L = 4$，贪心检查将一个区间覆盖单个段中的所有区间，因此返回 true。 如果$L$如果更小，则需要多个段，超过$k$。 

另一个边缘情况是当它们被隔离时：```
n = 5, k = 2
s = 10101
```如演练所示，小$L$强制每“1”执行一次操作，很快超过$k$。 贪心检查正确计算每个强制段。 

最后一个边缘情况是$k$足够大，任何$L=1$作品。 例如：```
n = 10, k = 10
s = 1010101010
```每个“1”都可以单独处理，因此答案变为 1。算法自然地处理这个问题，因为`can(1)`立即返回 true。
