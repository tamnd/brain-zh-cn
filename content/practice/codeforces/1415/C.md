 ## 解决方案
 ## 问题理解

 我们有一个表示关卡中单元格的二进制字符串。 一个`1`意味着平台已经存在，并且`0`意味着单元格是空的。 

球必须从该位置开始弹起`p`，然后访问位置`p + k`,`p + 2k`， 等等。 每一个职位都必须包含一个平台。 我们可以将平台添加到空单元中，并付费`x`每次添加。 

还有第二个操作：删除关卡的第一个单元格。 删除第一个单元格后，每个剩余的单元格都会向左移动一个位置。 这需要花费`y`每次移除。 我们可以重复这个操作，但是我们绝不能将水平缩短太多以致于位置`p`消失。 

目标是找到所需的最小总成本，以便在从前面删除一些次数并添加一些平台后，跳出序列变得有效。 

的最大值`n`是`10^5`，以及所有的总和`n`跨测试用例也至多`10^5`。 这立即排除了任何检查每个可能的起始位置然后每次重新扫描整个后缀的算法。 一个`O(n²)`解决方案将执行大约`10^10`最坏情况下的操作。 我们需要每个测试用例接近线性时间。 

一个微妙的点是删除单元格会改变位置`p`结束了。 认为：```
n = 5
p = 3
k = 2
s = 00100
```如果我们从前面删除一个单元格，则新位置`p`对应原始索引`4`，不是原始索引`3`。 任何独立处理删除和添加的解决方案都会计算出错误的答案。 

另一个容易犯的错误是忘记了只有间隔的位置`k`事情。 例如：```
n = 6
p = 2
k = 3
s = 000100
```所需的单元格是位置`2`和`5`。 位置`3`和位置`4`是无关紧要的。 试图使整个后缀变得良好的幼稚实现会付出不必要的添加的代价。 

第三种边缘情况发生在字符串末尾附近：```
n = 5
p = 5
k = 2
s = 00000
```唯一位置`5`是必须的。 答案只是一项补充。 当计算涉及的转换时，粗心的代码通常会访问超出数组末尾的内容`i + k`。 

## 方法

 最直接的解决办法就是尝试所有可能的前面删除次数。 

如果我们删除`d`单元格，然后定位`p`在新字符串中对应的位置`p + d`在原始字符串中。 从该位置开始，我们可以遍历索引```
p + d,
p + d + k,
p + d + 2k,
...
```并计算其中当前包含多少个`0`。 每个这样的单元都需要添加一个平台。 总成本变为：```
d * y + additions * x
```尝试所有有效值`d`很容易。 问题在于计数步骤。 如果我们重新扫描每个删除计数的弹跳位置，我们可能会花费`O(n)`每个候选人的工作。 由于有`O(n)`候选人，总数变为`O(n²)`。 

关键的观察是每个候选人的起始位置都会问同样的问题：

 > 从该索引开始并跳跃的算术级数中出现了多少个零`k`？ 

这些答案严重重叠。 如果我们已经知道位置的答案`i + k`，然后定位`i`区别仅在于是否有细胞`i`本身为零。 

定义：```
dp[i] = number of additions needed
        if bouncing starts at i
```使用从 0 开始的索引，```
dp[i] = (s[i] == '0') + dp[i + k]
```什么时候`i + k`存在。 否则，```
dp[i] = (s[i] == '0')
```此递归精确计算从以下位置开始沿所需弹跳路径丢失的平台数量`i`。 

一旦全部`dp[i]`值已知，可以在恒定时间内评估每个删除计数：```
cost = deletions * y + dp[start] * x
```在哪里`start`是变成位置的原始位置`p`删除后。 

这将问题转化为线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 转换`p`到从 0 开始的索引。 
2. 创建数组`dp`长度`n`。 
3. 从右到左处理位置。 
4. 对于每个位置`i`，计算：```
need = 1 if s[i] == '0' else 0
```5. 如果`i + k < n`， 添加`dp[i + k]`:```
dp[i] = need + dp[i + k]
```否则：```
dp[i] = need
```这给出了如果弹跳开始于以下位置则必须添加的平台数量`i`。 
6. 考虑每一种可能的删除次数。 

如果我们删除`d`单元格，原始字符串中所需的起始位置变为：```
start = p + d
```7. 对于每个有效`start`，计算：```
cost = (start - p) * y + dp[start] * x
```第一项是删除成本，第二项是在弹跳路径上添加所有缺失平台的成本。 
8. 在所有候选者中取最小值。 

### 为什么它有效

 对于任何索引`i`，弹跳路径由以下部分组成：```
i, i + k, i + 2k, ...
```复发```
dp[i] = missing_at_i + dp[i + k]
```计算该路径上零的数量。 每一个零都需要添加一个平台，并且每一个都已经满足要求。 

删除后`d`细胞、位置`p`在新的级别对应的位置`p + d`在原来的水平上。 所需添加的内容正好是`dp[p + d]`。 由于删除和添加独立地影响总成本，因此评估```
d * y + dp[p + d] * x
```对于每个有效的`d`检查每个可行的最终配置。 这些值中的最小值就是最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, p, k = map(int, input().split())
        s = input().strip()
        x, y = map(int, input().split())

        p -= 1

        dp = [0] * n

        for i in range(n - 1, -1, -1):
            dp[i] = (s[i] == '0')
            if i + k < n:
                dp[i] += dp[i + k]

        best = 10**18

        for start in range(p, n):
            deletions = start - p
            cost = deletions * y + dp[start] * x
            best = min(best, cost)

        ans.append(str(best))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```动态规划数组是从右到左填充的，因为每个状态都取决于`i + k`，位于右侧。 

表达式```
(s[i] == '0')
```评估为`True`或者`False`，Python 自动将其视为`1`或者`0`在算术表达式中。 这给出了当前单元格所需的添加数。 

循环结束`start`代表所有可能的删除计数。 如果`start = p`，没有细胞被去除。 如果`start = p + 1`，移除一个单元格，依此类推。 

最常见的实施错误是混合基于 1 的索引和基于 0 的索引。 输入位置`p`是从 1 开始的，但所有数组访问都是从 0 开始的，所以我们立即这样做：```
p -= 1
```另一个常见的错误是忘记只有通过重复大小跳跃才能到达的位置`k`事情。 递归自然地准确地捕获了这些位置。

 ## 边缘情况

 考虑：```
1
5 3 2
00100
1 1
```没有删除时，弹跳路径从位置开始`3`并访问位置`5`。 两者都是`1`和`0`，因此需要添加一项。 

如果我们删除一个单元格，位置`p`现在对应于原始位置`4`。 路径完全改变。 该算法处理这个问题是因为它评估`dp[2]`,`dp[3]`， 和`dp[4]`分别地。 它从不假设弹跳路径是固定的。 

现在考虑：```
1
6 2 3
000100
5 1
```相关职位仅`2`和`5`。 细胞`3`,`4`， 和`6`没关系。 大小跳跃后重复发生`k`，因此那些不相关的单元格永远不会影响计算的成本。 

最后，考虑：```
1
5 5 2
00000
3 1
```弹跳路径仅包含最后一个单元格。 DP建设过程中，`i + k`位于数组之外，因此递归正确停止：```
dp[4] = 1
```答案正好是一个加法，成本`3`。 不会发生越界访问，也不会计算额外的单元格。
