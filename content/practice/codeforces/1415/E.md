 ## 解决方案
 ## 问题理解

 每个boss都有其价值`c[i]`。 当我们击败老板时，我们获得当前的奖金作为分数，然后该老板将奖金更改为`c[i]`。 

如果没有重置的话，boss的顺序将完全决定每个boss的出现次数。`c[i]`对未来的分数有贡献。 正值通常应该尽早应用，因为它会增加许多以后的奖励，而负值通常应该延迟应用。 

重置操作创造了一个有趣的转折。 重置会将当前奖励设置回零，但被击败的头目将保持被击败状态，并且保留累积分数。 因为我们最多可能重置`k`有时，整个 Boss 战序列最多有效地分为`k + 1`独立的部分。 每个段内，奖金正常累积。 在分段之间，奖金被清除。 

我们需要在一次击败所有 Boss 后获得最大可能的总分。 

约束是第一个主要线索。 我们最多有`5 * 10^5`老板和`5 * 10^5`允许重置。 任何尝试检查排列、位置动态规划甚至`O(n^2)`过渡是没有希望的。 有五十万个元素，我们需要一些东西`O(n log n)`。 

一些边缘情况很容易被忽略。 

考虑```
1 100
-5
```答案是`0`。 

无论有多少次重置，都只有一个 Boss。 我们在申请之前获得当前奖金`-5`，所以分数永远不会改变。 

考虑```
3 2
-1 -2 -3
```答案是`0`。 

与一个boss战斗，重置，与另一个boss战斗，重置，与最后一个boss战斗。 每场战斗都会有奖金`0`，所以每个奖励都是`0`。 假设重置仅在正累积后有用的解决方案将错过这一点。 

考虑```
4 0
10 -100 10 10
```保持原来的顺序是无法得到答案的。 秩序完全在我们的控制之下，最优的安排必须利用这种自由。 

整个问题实际上是关于排列值并决定重置在哪里划分序列。 

## 方法

 A brute-force view is straightforward. 选择 Boss 的顺序，选择发生重置的位置，模拟该过程，并保留最佳答案。 

这是正确的，因为它从字面上列举了每一个有效的策略。 

不幸的是，有`n!`甚至在考虑重置位置之前就可能进行排序。 为了`n = 5 * 10^5`，这已经超出了天文数字。 

为了找到结构，让我们关注两次重置之间的固定部分。 

假设一个段包含值```
a1, a2, ..., am
```如果我们按照这个顺序处理它们，那么`a1`影响接下来的奖金`m - 1`打架，`a2`影响下一个`m - 2`打架等等。 

该部门的贡献变为```
a1(m-1) + a2(m-2) + ... + am(0)
```系数从左到右递减。 

这立即意味着交换争论。 如果两个值满足`x > y`, 放置`x`早一点总没有坏处，因为早一点的位置有更大的系数。 

因此，每个段都应该按非递增顺序排序。 

现在放眼全球。 我们最多有`k + 1`段。 排序后，每个段只是一个递减序列。 

将每个部分想象成一堆，其当前总和等于该部分内的累积奖金。 

当我们将一个新值放入一个段中时，该值将准确地贡献当前堆总和的答案。 之后，堆总和会增加我们插入的值。 

应首先分配最大值。 将全局所有boss值按降序排序后，我们一一进行处理。 

任何时候我们都有`k + 1`段总和。 为了最大化下一个值的直接贡献，我们应该将其放入当前总和最大的段中。 然后将当前总和添加到答案中。 

这将问题变成了一个贪婪的过程`k + 1`段总和。 

我们将段总和保存在最大堆中。 最初全部`k + 1`段有总和`0`。 

对于按降序排列的每个值：

 1.取最大的当前段和`s`。 
2.添加`s`到答案。 
3. 将值放入该段，求和`s + value`。 
4. 将更新后的总和返回到堆。 

这准确地构造了最佳分区和排序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!·n) | O(n!·n) | O(n) | 太慢了|
 | 最优贪婪 + 堆 | O(n log n) | O(n log n) | O(k) | 已接受 |

 ## 算法演练

 1. 读取所有boss增量。 
2. 按降序对值进行排序。 

在任何段内，较大的值应始终比较小的值出现得更早，因为较早的位置具有较大的系数。 
3.创建`k + 1`段。 

仅用其当前累计总和来表示每个段。 最初每个段总和等于`0`。 
4. 将所有段总和存储在最大堆中。 

Python 提供了一个最小堆，因此可以存储负值。 
5. 从大到小处理排序后的值。 
6. 提取电流和最大的段。 

如果当前总和是`s`，然后将下一个值放入该段中将完全贡献`s`至总分。 
7. 添加`s`到答案。 
8. 将段总和更新为`s + value`并将其推回堆中。 
9. After all values are processed, output the accumulated answer.

 ### 为什么它有效

 After fixing the segment boundaries, every segment must be sorted in descending order because earlier positions have larger coefficients. This reduces the problem to distributing values among`k + 1`段。 

当从最大到最小处理值时，每个未来值都小于或等于当前值。 关于段的唯一重要信息是其当前总和，因为将值插入到该段中会立即将该总和准确地贡献给答案。 

在每一步中，将当前值分配给具有最大总和的段可以提供最大可能的直接增益。 由于后来的值不大于当前值，因此将当前值移至其他位置并不能创造更好的未来补偿。 贪婪的选择总是安全的。 

堆模拟准确地执行了这个最佳分配过程，产生了最大可能的分数。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    c = list(map(int, input().split()))

    c.sort(reverse=True)

    heap = [0] * (k + 1)
    heapq.heapify(heap)

    ans = 0

    for x in c:
        s = -heapq.heappop(heap)
        ans += s
        heapq.heappush(heap, -(s + x))

    print(ans)

if __name__ == "__main__":
    solve()
```第一步是以降序对值进行排序。 这会强制执行每个段内的最佳排序。 

堆存储当前段的总和。 因为 Python 的堆是最小堆，所以我们对每个值取负，以便最大的段和首先出现。 

对于每个排序值，我们删除最大的段和`s`， 添加`s`对于答案，将该段更新为`s + x`，然后将其插回。 

所有算术都使用 Python 整数，它可以安全地处理最大可能的答案。 和`n = 5 * 10^5`和值高达`10^6`，64 位算术已经足够了，但 Python 的任意精度消除了任何担忧。 

最常见的实现错误是直接使用最小堆而不是最大堆。 贪心选择要求最大的当前段和。

import heapq

def solve():

 ## 边缘情况

 考虑```
1 100
-5
```排序后我们有`[-5]`。 堆包含`101`零。 

我们提取`0`， 添加`0`到答案，然后推动`-5`。 

最终的答案是```
0
```额外的重置并不重要，因为分数是在老板修改奖金之前授予的。 

考虑```
3 2
-1 -2 -3
```排序顺序是```
[-1, -2, -3]
```堆开始于`[0, 0, 0]`。 

每一步都会提取一个零值段并贡献`0`到答案。 每个负值都被隔离在自己的段中。 

最终的答案是```
0
```这证实了算法在提高分数时自然会使用可用的重置。 

考虑```
4 0
10 -100 10 10
```排序后的顺序变为```
[10, 10, 10, -100]
```段总和演变为```
0 -> 10 -> 20 -> 30 -> -70
```收集到的分数是```
0 + 10 + 20 + 30 = 60
```等等，每一步都将更新前的当前总和相加：```
0 + 10 + 20 + 30 = 60
```该算法正确地将大的正值放在前面，并将大的负值推迟到最后，完全匹配最佳排序。 在这种情况下，将输入顺序视为固定会失败。
