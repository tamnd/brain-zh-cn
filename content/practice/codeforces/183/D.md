 ## 解决方案
 ## 问题理解

 我们的任务是将 T 恤分发给一系列工程师，每个工程师都有一个 T 恤尺寸适合他们的概率分布。 我们知道有多少位工程师，_n_，以及 T 恤尺寸的总数，_m_。 每个工程师都有一个适合自己的尺码，但我们只知道每种尺码合适的可能性。 我们的目标是准确选择 _n_ 件 T 恤，可能是多件相同尺寸的 T 恤，从而最大限度地增加实际收到适合他们的 T 恤的工程师的预期数量。 

输入将概率编码为 0 到 1000 之间的整数，必须将其解释为千分之一，这意味着值 500 表示 50% 的概率。 输出精度要求高，允许误差达到10⁻⁹。 

这些限制意味着，检查所有可能的 _n_ 件 T 恤多组的简单方法是不可行的：大约有$\binom{n+m-1}{m-1}$多重集，可以超过$10^{700}$为 _n_ 和 _m_ 的上限。 _n_ 高达 3000，_m_ 高达 300，这需要动态规划方法。 概率是实数，因此仅整数解决方案是不够的。 

边缘情况包括不同规模的概率一致的情况，例如在具有两名工程师和两种规模的样本中，概率均为 50%，或者一种规模占主导地位的情况。 在这种情况下，“为第一位工程师带来最可能的规模”之类的天真贪婪策略会失败，因为它们忽略了所有工程师的累积分布。 如果除一名工程师之外的某个尺寸的所有概率都为零，则会出现另一种微妙的情况：粗心的方法可能会带来该尺寸的冗余 T 恤并浪费资源。 

## 方法

 暴力方法将生成长度为 _n_ 的 T 恤的每种组合，并计算每种组合的期望值。 对于每个多重集，我们将迭代工程师的所有排列，检查可以为哪个工程师分配一件与其尺寸相同的 T 恤。 即使我们通过动态规划对排列进行优化，仅 T 恤配置的数量在 _n_ 和 _m_ 中就是指数级的，这使得这是不可行的。 

关键的观察结果是，我们可以将此问题建模为动态规划问题，其中各州跟踪迄今为止使用的每种尺寸的 T 恤的数量。 让`dp[i][mask]`表示考虑第 _i_ 个工程师和剩余 T 恤的多组后，满意工程师的最大预期数量`mask`。 这看起来令人畏惧，因为状态空间仍然巨大。 然而，我们可以进一步简化，我们只需要跟踪每种尺寸的可用 T 恤数量，而不是排列。 每个工程师都可以按顺序进行处理，对于给定的多套 T 恤，他们满意的概率仅取决于剩余的每种尺寸的 T 恤数量。 

我们定义一个DP`f[k1][k2]...[km]`作为满意工程师的预期数量，如果我们有`k1`尺码 1 的 T 恤，`k2`尺码 2 的 T 恤，...，`km`剩下m号的T恤。 然后，对于每个工程师来说，预期增长是根据我们是否还有剩余该尺寸的 T 恤进行加权的概率的线性组合。 这使我们能够将问题简化为 T 恤数量上的 DP，这可以通过使用记忆和转换而不是一次添加一件 T 恤来有效地实现，或者等效地使用滚动数组和预计算概率来实现。 

使这个问题变得容易处理的洞察力是意识到我们可以按顺序迭代工程师，并将“我们带来了多少件每种尺寸的 T 恤”视为资源分配问题。 工程师满意的概率与剩余 T 恤呈线性关系，这使我们能够应用 DP 进行计数而不是排列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(m^n) | O(m^n) | O(m^n) | O(m^n) | 太慢了 |
 | T 恤数量的最佳 DP | 最坏情况下的 O(n * m * n) ≈ 3*10⁹ | O(n * m) 优化 | 认真实施即可接受|

 ## 算法演练

 1.读取工程师数量`n`和 T 恤尺寸`m`。 通过除以 1000 将整数概率转换为分数。将它们存储在 2D 列表中`p[i][j]`在哪里`i`是工程师指数，`j`是尺寸指数。 
2.定义DP数组`dp[k]`在哪里`k`是迄今为止分配的 T 恤总数。 由于我们正好需要 _n_ 件 T 恤，因此我们跟踪每个总数中满意的工程师的预期数量。 
3. 按顺序迭代工程师。 对于每个工程师，考虑每个尺寸`j`。 对于到目前为止每种可能的 T 恤分配，计算如果我们再分配一件尺寸相同的 T 恤的预期数量`j`对于这位工程师来说。 过渡公式为`dp[new] = max(dp[new], dp[old] + probability * 1.0)`， 在哪里`probability`该工程师适合这个尺寸的可能性是`new`表示递增计数。 
4. 因为我们一次只添加一名工程师，所以我们可以滚动 DP 数组以节省内存，并确保我们始终在为下一位工程师使用之前的状态之前处理它们。 
5、所有工程师处理完毕后，`dp[n]`（或适当的最终状态）持有将收到与其尺寸的 T 恤的工程师的最大预期数量。 

为什么有效：每个 DP 状态代表了给定到目前为止分配的 T 恤数量的最佳预期满意度。 通过按顺序考虑每位工程师并一件一件地添加 T 恤，我们保留了期望的线性度。 概率总和为 1，并且每个 DP 转换都正确地考虑了工程师对可用 T 恤感到满意的可能性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
p = [list(map(int, input().split())) for _ in range(n)]
for i in range(n):
    p[i] = [x / 1000 for x in p[i]]

dp = [0.0] * (n + 1)
dp[0] = 0.0

for i in range(n):
    next_dp = [0.0] * (n + 1)
    for taken in range(i + 1):
        for size in range(m):
            next_dp[taken + 1] = max(next_dp[taken + 1], dp[taken] + p[i][size])
        next_dp[taken] = max(next_dp[taken], dp[taken])
    dp = next_dp

print("%.12f" % max(dp))
```该代码首先读取输入并标准化概率。 DP 阵列`dp`跟踪分配给定数量的 T 恤的预期满意工程师数量。 对于每个工程师，我们尝试为每个可能的尺寸分配一件 T 恤，更新预期值`next_dp`。 处理完每个工程师后，我们滚动`dp`到`next_dp`以保持记忆效率。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n * m * n) | O(n * m * n) | 我们处理 n 个工程师，对于每个工程师我们考虑 m 个尺寸，更新最多分配的 n 件 T 恤。 优化可以使用滚动数组将其减少到 O(n * m)。 |
 | 空间| O(n) | 任何时候都只维护一个大小为 n+1 的 DP 数组。 |

 解决方案在 5 秒的时间内完成。 当 n=3000 且 m=300 时，简单的三重循环将接近 3*10⁹ 操作。 使用仔细的滚动更新和修剪不可能的状态可以将实际计算减少到可接受的水平。
