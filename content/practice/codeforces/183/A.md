 ## 解决方案
 ## 问题理解

 汽车从无限二维网格上的某个地方出发，最终到达了冰淇淋摊位`(0, 0)`。 我们知道移动的次数和 GPS 记录的顺序，但每个记录只告诉我们该步骤的一组可能的方向。 

例如，`"UR"`意味着走势要么向上，要么正确。`"ULDR"`意味着移动可能是四个方向中的任何一个。 

我们需要计算有多少个起始位置可能导致`(0, 0)`处理完所有动作后。 

思考问题的一个直接方法是逆向过程。 不要问汽车从哪里开始，而是问如果开始于每一步，它可能会在哪里`(0, 0)`并向后浏览移动描述。 此逆过程中的每个有效结束位置都对应于一个可能的总部位置。 

移动次数最多为`2 * 10^5`，因此任何显式存储所有可达点的算法都是不可能的。 即使每一步只使状态数量增加一倍，我们也会很快达到天文数字。 二次解在这里也太慢了。 由于 2 秒的限制，我们应该期望接近线性时间。 

关键的挑战是，可到达位置的集合看起来呈几何级数增长，但实际上具有非常严格的结构。 缺少该结构会导致不必要的状态爆炸。 

一个容易犯的错误是独立处理 x 坐标和 y 坐标而不检查奇偶校验约束。 

考虑：```
1
UR
```汽车可以向右或向上移动。 反过来说，总部可能位于`(-1,0)`或者`(0,-1)`。 只有`2`可能性，并非所有点都在矩形内。 

另一个微妙的情况是重复无限制的动作：```
2
ULDR
ULDR
```经过两次任意移动后，可到达的位置并不是一个图中的每个点`5 x 5`正方形。 曼哈顿距离平价很重要。 有效的总部位置恰好是与原点距离最大的点`2`并且具有相同的奇偶性`2`。 

粗心的矩形计数解决方案会在这里严重计数。 

还有一种退化情况，即每次移动都强制相同的轴方向。```
3
UR
UR
UR
```每次移动都会改变 x`+1`或 y 由`+1`。 反过来说，每个总部职位都满足：```
x <= 0
y <= 0
x + y = -3
```答案只是`4`，不是面积大小的数量。 

可达集的结构就是整个问题。 

## 方法

 蛮力的想法很简单。 每次移动后维护所有可能位置的集合。 开始于`(0,0)`。 对于每个当前点，应用当前 GPS 记录中每个允许的方向，并将结果点插入到新的集合中。 

这是正确的，因为它显式模拟了所有有效路径。 问题是增长。 和`n = 2 * 10^5`，可达点的数量可以与`n^2`。 显式存储和更新所有这些将需要大约`10^10`最坏情况下的操作。 

我们需要了解这些状态在几何上实际上是什么样子。 

每一次移动都会改变一个坐标`±1`。 后`n`移动，每个可达点的曼哈顿距离奇偶性等于`n`。 

现在看看五种可能的记录类型。`"UR"`x 或 y 总是增加`1`。`"DL"`x 或 y 总是减少`1`。`"UL"`增加 y 或减少 x。`"DR"`减少 y 或增加 x。`"ULDR"`允许任何方向。 

我们可以跟踪两个变换后的坐标上的约束，而不是跟踪每个点：```
s = x + y
d = x - y
```每一步都会影响这些值之一`±1`。 

例如：

 | 移动| s 的变化 | d | 的变化
 | ---| ---| ---|
 | 你| +1 | -1 |
 | d | -1 | +1 |
 | 左 | -1 | -1 |
 | 右 | +1 | +1 |

 现在检查每个记录类型。`"UR"`总是增加`s`经过`1`。`"DL"`总是减少`s`经过`1`。`"UL"`总是减少`d`经过`1`。`"DR"`总是增加`d`经过`1`。`"ULDR"`允许两个变换轴上的任一方向。 

这将问题完全分开。 

认为：```
a = count("UR")
b = count("DL")
c = count("DR")
d = count("UL")
e = count("ULDR")
```然后：```
s = a - b + variable
d = c - d + variable
```其中每个变量都来自不受限制的移动和变化`2`。 

更准确地说：```
s ∈ [a - b - e, a - b + e]
d ∈ [c - d - e, c - d + e]
```并且两个值都与其中心具有相同的奇偶性。 

每个有效对`(s,d)`精确确定一个网格点：```
x = (s + d) / 2
y = (s - d) / 2
```奇偶校验条件自动保证完整性。 

所以答案就变成了：```
(number of possible s values) *
(number of possible d values)
```每个间隔以以下步骤进行`2`，所以每个都有`e + 1`的可能性。 

最终答案：```
(e + 1)^2
```与状态空间的表面复杂性相比，这小得惊人。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) 到 O(n³)，具体取决于实施 | O(n²) | 太慢了 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取所有移动记录。 

我们只关心每种类型出现的次数。 一旦我们移动到变换后的坐标，它们的确切顺序并不重要。 
2.统计有多少条记录`"ULDR"`。 

设这个数为`e`。 
3. 观察其他移动类型的强制行为。`"UR"`总是增加`s = x + y`。`"DL"`总是减少`s`。`"DR"`总是增加`d = x - y`。`"UL"`总是减少`d`。 

这些移动会产生固定的偏移量并且不会产生分支。 
4.观察行为`"ULDR"`。 

每个不受限制的动作都可以独立改变`s`通过任一`+1`或者`-1`，类似地对于`d`。 

后`e`这样的移动，每个变换后的坐标都有`e + 1`可达到的值，因为值因步长而异`2`。 
5. 增加可能性。 

的选择`s`和`d`是独立的。 每个有效对恰好对应于一个整数网格点。 

总部职位数量为：```
(e + 1)²
```### 为什么它有效

 转变：```
s = x + y
d = x - y
```解耦运动约束。 

每个非`"ULDR"`记录精确地修复了一个变换后的坐标变化并且不留下任何分支。 仅有的`"ULDR"`创造选择，并且每一个这样的举动都会独立地贡献一个二元决策`s`和一个二元决定`d`。 

后`e`不受限制的移动，两个变换后的坐标都可以精确取`e + 1`不同的值，因为可达值形成具有差异的算术级数`2`。 

之间的映射`(s,d)`和`(x,y)`是匹配奇偶校验值的双射，因此计算变换坐标对与计算网格点完全相同。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

free_moves = 0

for _ in range(n):
    s = input().strip()
    if s == "ULDR":
        free_moves += 1

print((free_moves + 1) ** 2)
```该实现很小，因为数学简化消除了所有几何图形。 

影响总部可能职位数量的唯一信息是存在多少完全不受限制的调动。 每个受约束的移动只会移动最终可到达的区域，而不会改变其大小。 

该公式仅使用整数运算，因此不存在精度问题。 即使在最大约束下：```
(200000 + 1)^2
```可以轻松地放入 Python 整数中。 

一个常见的实施错误是尝试模拟坐标或维护可达集。 这种方法速度较慢且更容易出错，因为奇偶校验约束变得难以正确管理。 

## 工作示例

 ### 示例 1

 输入：```
3
UR
UL
ULDR
```我们处理移动类型。 

| 步骤| 记录| 自由移动 |
 | ---| ---| ---|
 | 1 | 你 | 0 |
 | 2 | UL | 0 |
 | 3 | ULDR | 1 |

 最终计算：```
(1 + 1)^2 = 4
```等等，示例答案是`9`，所以我们需要仔细解释。 

原来的路径是从总部到`(0,0)`。 反转方向可以保留计数，但会改变移动方向。 更重要的是，每个不受限制的移动都会在变换后的坐标中贡献三个可达值，而不是两个。 

让我们正确推导一下。 

后`e`不受限制的动作：```
s ∈ center + {-e, -e+2, ..., e}
```可能性的数量：```
e + 1
```同样对于`d`。 

对于此示例，实际上有一个不受限制的移动和两个部分受限的移动，每个移动仍然在一个变换后的坐标中创建分支。 

我们直接计算一下。`UR`给出了两种可能性`(s,d)`：`(+1,+1)`或者`(+1,-1)`。`UL`给出：`(+1,-1)`或者`(-1,-1)`。`ULDR`给出所有四种组合。 

两个变换后的坐标各有`3`可能的值总计，产生：```
3 * 3 = 9
```这揭示了更深层次的简化：

 每一步都为一个变换后的坐标贡献一个独立的二元选择。 

更具体地说：

 | 记录| 固定坐标 | 可变坐标|
 | ---| ---| ---|
 | 你 | s = +1 | d = ±1 |
 | DL | s = -1 | d = ±1 |
 | UL | d = -1 | s = ±1 |
 | 博士| d = +1 | s = ±1 |
 | ULDR | 两个变量 | |

 所以我们应该计算有多少步允许变化`s`以及有多少允许变化`d`。 

定义：```
cs = count(UL) + count(DR) + count(ULDR)
cd = count(UR) + count(DL) + count(ULDR)
```然后：```
answer = (cs + 1) * (cd + 1)
```现在继续修正后的推导。 

对于样本：```
cs = 1 + 0 + 1 = 2
cd = 1 + 0 + 1 = 2
```回答：```
3 * 3 = 9

该迹线展示了坐标解耦不变量。 一个变换后的坐标可以保持固定，而其他坐标可以自由分支。

# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())

    cs = 0
    cd = 0

    for _ in range(n):
        s = input().strip()

        if s == "UR":
            cd += 1
        elif s == "DL":
            cd += 1
        elif s == "UL":
            cs += 1
        elif s == "DR":
            cs += 1
        else:
            cs += 1
            cd += 1

    print((cs + 1) * (cd + 1))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out
