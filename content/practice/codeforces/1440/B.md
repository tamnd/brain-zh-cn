 ## 解决方案
 ## 问题理解

 我们得到了一个排序列表$nk$数字并要求将其分成$k$组，每个组恰好包含$n$元素。 分割完成后，我们使用排序顺序中的上中间位置计算每个组的中位数，并且我们希望所有这些中位数的总和尽可能大。 

关键的限制是我们不能无成本地在组内任意重新排序输入数组，但全局数组已经排序。 该任务完全是关于如何将连续值划分为组，以便所选的中值位置变得尽可能大。 

约束允许最多$2 \cdot 10^5$所有测试用例的总元素。 这立即排除了任何尝试模拟所有可能的分区或重复排序子集的解决方案。 任何方法在每个测试用例的数组大小上都必须基本上是线性的，或者在最坏的情况下$O(nk \log(nk))$，尽管排序是不必要的，因为数组已经排序了。 

出现微妙的边缘情况时$n = 1$。 在这种情况下，每个元素都是其自己的中位数，因此答案只是数组的总和。 试图“平衡”群体的幼稚分组策略很容易错过这种简化。 

另一个不明显的极端情况发生在$k = 1$。 那么我们只有一组，所以答案就是整个数组的中位数，即索引处的元素$\lceil nk/2 \rceil$。 

当两者都存在时，主要的困难就出现了$n$和$k$很大，因为我们必须决定如何分配元素，以便中位数来自最大可能的可用值。 

## 方法

 如果我们考虑暴力破解，我们会尝试所有可能的方法将已排序的数组拆分为$k$大小组$n$。 即使我们限制自己维持秩序，选择位置的方法的数量也是组合的，按多项系数的顺序。 为了$nk \le 2000$，这已经是不可行的了； 为了$2 \cdot 10^5$，这是完全不可能的。 

关键的观察是数组是排序的，我们只关心中位数，而不是完整的组结构。 每组内尺寸$n$，中位数是位置处的元素$\lceil n/2 \rceil$。 因此，每个小组贡献一个“重要”元素，其余的只是确保可行性的约束。 

这表明我们应该考虑选择$k$数组中的中值位置。 如果我们想象从最大值向后贪婪地构建组，结构就会变得更加清晰：为了最大化中位数，我们希望每个中位数尽可能大，但我们被迫“花费”它周围的其他元素来完成每个组。 

每个中位数有效消耗$n - 1$支持要素。 由于我们想要最大化中位数，因此我们应该将最大的可用元素指定为中位数，但我们必须确保保留足够的元素以形成有效的组。 

如果我们从最大值开始处理，每次选择中位数时，我们都必须跳过足够多的元素，以便完成该组。 最佳模式是确定性的：我们反复将一个元素作为中位数，然后丢弃$n - 1$否则会干扰形成有效群体的元素。 

同样，我们可以从数组的末尾开始工作，并从由下式确定的特定偏移量开始选择每隔一个元素$n$。 所选中位数之间的间距恰好是$n - 1$，但由于组在排序结构中重叠，因此有效步骤变为$n - 1$从右向左扫描时，元素会在连续选定的中位数之间跳过。 

因此，最优解决方案减少为选择$k$以固定间隔从排序数组中提取元素。

 ## 算法演练

 1. 计算$m = \lceil n/2 \rceil$，这是任何组内的中间位置。 这告诉我们排序时中位数距其组的开头有多远。 
2. 从末尾开始处理全局排序数组，因为较大的值应尽可能贡献于中位数。 
3.从索引开始$nk - 1$，选择元素作为中位数，同时以大小为步长向左移动$n - m + 1$或者，更简单地说，通过从分组约束导出的模式：每次我们选择一个中位数时，我们都会跳过$n - m$必须属于同一组或前一组的元素。 

干净的实现进一步简化了这一点：我们向后移动并选择每一个$(n - m + 1)$-从特定偏移量开始的第一个元素。 
4.准确收集$k$这样的元素，因为有$k$团体，因此$k$中位数。 
5. 对这些选定元素求和并输出结果。 

微妙之处在于我们没有明确地构建群体。 相反，我们模拟分组所施加的约束：每个中位数的右侧必须有足够的元素（按排序顺序）来填充其组。 

### 为什么它有效

 不变的是，在选择中位数后，我们总是留下足够的未使用元素来为所有剩余的中位数形成完整的组。 由于数组已排序，因此从右侧取中位数可以最大化其值，并且精确跳过所需数量的元素可确保可行性，而不会在非中位数位置上浪费较大的元素。 任何提前选择较小中位数的偏差都会直接减少总和或迫使更大的元素进入非中位数槽，这不能增加总数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        # median position in each group (1-indexed)
        m = (n + 1) // 2
        
        # step size between useful medians when scanning from right
        step = n - m + 1
        
        # start from the last element
        idx = len(a) - step
        
        ans = 0
        
        for _ in range(k):
            ans += a[idx]
            idx -= step
        
        print(ans)

if __name__ == "__main__":
    solve()
```该实现完全基于排序数组上的索引算术。 关键是计算所选中位数之间的正确间距。 变量`m`确定中位数位于每个组内的位置，并从中得出必须跳过多少个元素，以便每个选定的中位数可以属于有效组而不会重叠。 

向后遍历确保我们始终选择最大的可用有效候选者。

 ## 边缘情况

 当$n = 1$，每个元素都是它自己的组，也是它自己的中位数。 该算法简化为通过步骤 1 选择每个元素。索引算术仍然有效，因为$m = 1$给出`step = n - m + 1 = 1`，所以我们只需对整个数组求和即可。 

什么时候$k = 1$，我们只选择一个元素。 起始索引成为整个数组的正确中值位置，因为`step`将第一个选择的索引与全局中位位置对齐。 该算法有效地返回排序数组的中心元素。 

当所有值都相等时，每个分组都会产生相同的中位数。 该算法仍然选择均匀间隔的元素，但无论分区如何，总和都保持一致，从而确认简并下的正确性。 

在边界情况下，$n$很大并且$k$很小，步长确保我们永远不会过度消耗元素，因为每个选择的中位数隐式保留足够的元素以在其周围形成有效的组。
