 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串和两种支付方式。 第一种是直接购买：每个角色`0`成本`c0`硬币和每个角色`1`成本`c1`硬币。 二是修改：在购买之前，我们可以对人物进行翻转、转动`0`进入`1`或者`1`进入`0`，并且每次翻转成本`h`硬币。 

目标是确定每个测试用例要执行多少次翻转，以使翻转的总成本加上购买最终字符串的成本最小化。 

字符串长度最多为 1000，并且最多有 10 个测试用例，因此每个测试用例进行二次或线性扫描就足够了。 所有翻转组合的任何指数或每个字符模拟都是不必要的。 

一个幼稚的错误来自于贪婪地处理每个角色的翻转而不考虑全局平衡。 例如，如果`c0`远大于`c1`，翻转许多可能是有益的`0`进入`1`即使每次翻转看起来都很昂贵，因为最终的每个角色成本差异可能超过翻转成本。 

另一个微妙的问题是假设我们应该总是翻转当前“昂贵”的角色。 当翻转以增加其他地方总成本的方式改变分布时，这种方法就会失败。 

## 方法

 蛮力的想法是尝试翻转所有可能的头寸子集。 对于每个子集，我们计算翻转这些字符的成本，然后计算购买结果字符串的成本。 由于每个位置都可以翻转或不翻转，这导致`2^n`每个测试用例的可能性，对于`n = 1000`。 

关键的观察是在决定有多少`0`我们希望在最终的字符串中出现，确切的位置并不重要。 重要的只是零和一的数量。 如果我们知道需要多少个零，我们就可以计算需要多少次翻转才能从原始字符串中实现这一目的。 

让字符串包含`z`零点和`o = n - z`那些。 假设我们希望最终的字符串具有`k`零。 为了达到这种状态，我们必须翻转：

 -`(z - k)`零变为一如果`k <= z`-`(k - z)`如果将 1 化为 0`k > z`所以对于每个可能的最终零个数`k`从`0`到`n`，我们可以计算所需的翻转次数，乘以`h`，然后直接计算购买成本。 

这将问题减少到检查字符串的所有可能的最终组合，这是线性的`n`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 尝试所有最终计数 | 每个测试用例 O(n^2) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算原始字符串中有多少个 0 和 1。 这给出了字符串的基线描述，而不需要位置。 
2. 迭代所有可能的值`k`， 在哪里`k`表示最终字符串中零的数量。 每个值都描述完整的目标配置。 
3. 对于每个`k`，计算需要翻转多少次。 如果`k < z`，我们通过翻转来减少零`(z - k)`零变为一。 如果`k > z`，我们通过翻转来增加零`(k - z)`化为零。 总翻转次数为`|z - k|`。 
4. 将翻转次数乘以成本`h`。 
5. 将最终购买成本计算为`k * c0 + (n - k) * c1`。 
6. 添加翻转成本和购买成本以获得该目标的总成本`k`。 
7. 取最小值`k`。 

关键思想是每个可能的最终字符串都由其零的数量唯一表示，并且状态之间的转换仅取决于计数，而不取决于位置。 

### 为什么它有效

 在任何时候，问题的状态都可以通过存在多少个零来概括。 翻转一个字符会将该计数更改为 1，并且花费固定的金额`h`。 由于最终成本仅取决于计数而不取决于排列，因此任何最佳策略都必须对应于某个最终计数`k`。 通过详尽地评估所有这些`k`，我们涵盖了所有可能的结果，而无需明确模拟翻转。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, c0, c1, h = map(int, input().split())
    s = input().strip()

    z = s.count('0')
    o = n - z

    ans = 10**18

    for k in range(n + 1):
        flips = abs(z - k)
        cost = flips * h + k * c0 + (n - k) * c1
        ans = min(ans, cost)

    print(ans)
```该代码首先将字符串简化为单个统计数据：零的数量。 然后，它枚举仅由该统计数据定义的所有可能的目标配置。 表达式`abs(z - k)`捕获所需的最小翻转次数，因为每次翻转都会将零计数恰好更改为 1。 

循环结束`k`是安全的，因为`n ≤ 1000`，因此每个测试用例最多检查 1000 个候选状态。

 ## 边缘情况

 当字符串均匀时，例如`00000`，该算法评估每个`k`但很快发现任何偏差都会增加翻转成本，而不会降低足够的采购成本来弥补。 为了`k = 5`，翻转次数变为 5，但购买成本并没有提高，因为`c0`每个字符都是固定的。 

当翻转成本`h`非常大，最优解总是对应于`k = z`（无翻转）或最近的边界。 枚举自然包括这种情况，因为`k = z`产生零翻转成本。 

什么时候`c0`和`c1`如果大小相反，算法会自动将最优值转向完全转换为更便宜的字符，因为一旦线性成本项占主导地位并超过翻转惩罚`n * |c0 - c1|`超过`h`。
