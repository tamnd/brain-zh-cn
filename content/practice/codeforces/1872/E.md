 ## 解决方案
 ## 问题理解

 我们得到一个静态整数数组，但该数组根据二进制字符串动态分为两组。 每个位置 i 将其值 a[i] 贡献给组 0 或组 1，具体取决于 s[i] 是 0 还是 1。 

系统支持两种操作。 第一个操作翻转二进制字符串的整个段，将 0 变为 1，将 1 变为 0。这仅影响元素的分组方式，而不影响它们的值。 第二个操作要求对当前组与指定位 g 匹配的所有数组值进行异或。 

所以核心难点不是计算异或本身，而是在回答组异或查询的同时保持段翻转下的快速更新。 

约束很严格：每个测试用例 n 和 q 最多可达 10^5，测试之间的总和也有类似的界限。 这排除了每个查询从头开始重新计算 XOR 的可能性，因为这会导致最坏情况下的 O(nq)，这远远超出了限制。 

一种简单的方法是对每个查询的所有索引重新计算 XOR，但即使每个查询进行一次完整扫描，在最坏的情况下也已经给出了 10^10 次操作，这是不可行的。 

如果我们尝试维护两个正在运行的 XOR，但通过扫描整个范围在每次翻转时天真地更新它们，则会出现更微妙的失败情况。 对 n 个元素的单个大翻转查询仍将花费 O(n)，并且重复翻转会将性能降低到二次。 

关键的观察结果是，组上的异或仅取决于成员身份奇偶性，并且仅翻转切换成员身份。 这表明维持全局总量并跟踪翻转如何交换两组的含义。 

## 方法

 暴力解决方案通过迭代整个数组并检查 s[i] 是否等于 g 来重新计算每个查询类型 2 的 XOR。 这是正确的，因为它直接遵循定义，但它太慢了，因为每个查询的成本为 O(n)，并且最多可以有 10^5 个查询。 

效率低下的原因在于每次翻转后都要从头开始重新计算组成员资格。 重要的结构是类型 1 操作不会更改值，仅交换两个组之间的成员资格。 这意味着如果我们能够跟踪当前有多少元素属于每个组并在全局翻转状态下维护它们的 XOR 聚合，那么我们根本不需要接触单个元素。 

我们维护两个 XOR 累加器：一个用于原始字符串具有 0 的位置，另一个用于具有 1 的位置。如果我们跟踪某个位置已翻转的次数，则范围翻转不需要单独更新元素。 关键技巧是观察到只有翻转的奇偶性才重要，因此我们可以维护一个具有惰性传播的线段树，通过交换组聚合来翻转 XOR 贡献。 

每个线段树节点存储两个值：该线段中当前标记为 0 的元素的异或和当前标记为 1 的元素的异或。 翻转操作只是交换节点中的这两个值。 这使得范围翻转变得高效，并且合并保持一致，因为 XOR 是关联的。 

最终查询变成根节点的直接读取，具体取决于位 g 的当前解释。

 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(1) | O(1) | 太慢了 |
 | 带有延迟翻转的线段树 | O((n + q) log n) | O((n + q) log n) | O(n) | 已接受 |

 ## 算法演练

1. 构建一棵线段树，其中每个节点存储两个值：其线段中所有 a[i] 的异或（其中 s[i] 当前为 0），以及异或（其中 s[i] 当前为 1）。这种分离允许直接回答查询。 
2. 使用初始二进制字符串初始化叶节点。 如果s[i] = 0，则将a[i]放入零异或桶中； 否则进入一异或桶。 这对初始分区进行了精确编码。 
3. 合并两个子节点时，通过对相应的桶进行异或，为每个组独立计算异或。 这是可行的，因为 XOR 是关联的，并且不相交段中的元素不会相互干扰。 
4. 对于范围 [l, r] 上的类型 1 查询，对线段树应用延迟翻转操作。 在每个完全覆盖的节点处，交换组 0 和组 1 所存储的 XOR 值。这表示切换该段中的所有位。 
5. 如果节点被部分覆盖，则递归地传播操作，并通过在访问子节点之前将挂起的翻转下推来确保正确性。 
6. 对于带有g的类型2查询，直接返回根节点对应桶中存储的异或。 如果 g = 0，则返回 root.xor0，否则返回 root.xor1。 

### 为什么它有效

 每个元素在任何时候都只对两个 XOR 存储桶之一贡献一次。 对段的翻转操作会切换该段中每个元素的成员资格，这相当于交换该段的两个 XOR 累加器。 由于 XOR 是线性的，并且元素不会跨段交互，因此保持正确的值减少为在范围翻转下保持正确的分区。 延迟传播可确保每次交换在需要时准确应用，而无需重新计算逐个元素的状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, a, s):
        self.n = len(a)
        self.a = a
        self.s = s
        self.size = 4 * self.n
        self.x0 = [0] * self.size
        self.x1 = [0] * self.size
        self.lazy = [0] * self.size
        self.build(1, 0, self.n - 1)

    def build(self, v, tl, tr):
        if tl == tr:
            if self.s[tl] == '0':
                self.x0[v] = self.a[tl]
            else:
                self.x1[v] = self.a[tl]
            return
        tm = (tl + tr) // 2
        self.build(v * 2, tl, tm)
        self.build(v * 2 + 1, tm + 1, tr)
        self.pull(v)

    def pull(self, v):
        self.x0[v] = self.x0[v * 2] ^ self.x0[v * 2 + 1]
        self.x1[v] = self.x1[v * 2] ^ self.x1[v * 2 + 1]

    def apply(self, v):
        self.x0[v], self.x1[v] = self.x1[v], self.x0[v]
        self.lazy[v] ^= 1

    def push(self, v):
        if self.lazy[v]:
            self.apply(v * 2)
            self.apply(v * 2 + 1)
            self.lazy[v] = 0

    def update(self, v, tl, tr, l, r):
        if l > r:
            return
        if l == tl and r == tr:
            self.apply(v)
            return
        self.push(v)
        tm = (tl + tr) // 2
        self.update(v * 2, tl, tm, l, min(r, tm))
        self.update(v * 2 + 1, tm + 1, tr, max(l, tm + 1), r)
        self.pull(v)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        s = input().strip()
        q = int(input())

        st = SegTree(a, s)

        for _ in range(q):
            tmp = input().split()
            if tmp[0] == '1':
                l = int(tmp[1]) - 1
                r = int(tmp[2]) - 1
                st.update(1, 0, n - 1, l, r)
            else:
                g = int(tmp[1])
                if g == 0:
                    print(st.x0[1], end=' ')
                else:
                    print(st.x1[1], end=' ')
        print()

if __name__ == "__main__":
    solve()
```该实现使用线段树，其中每个节点维护两个 XOR 值。 构建步骤根据初始字符串将每个值分配到两个存储桶之一。 更新函数使用惰性传播执行范围翻转，其中翻转是通过交换两个存储的 XOR 值来实现的。 

推送功能通过传播待处理的翻转来确保下降到子级时的正确性。 更新后，拉函数会根据子节点重新计算父节点。 根始终包含当前 0 和 1 组之间的全局 XOR 分割，使得查询为 O(1)。 

一个微妙的点是翻转是对称的，所以我们不需要跟踪实际的位，只需要跟踪一个段是否被翻转了奇数次。 这正是惰性标志所编码的内容。 

## 工作示例

 ### 跟踪示例

 考虑一个简化的情况：

 数组：`[1, 2, 3, 4]`细绳：`0100`我们处理一个查询序列：

 | 步骤| 运营| x0（根）| x1（根）|
 | ---| ---| ---| ---|
 | 1 | 初始化| 1 + 3 + 4 = 6 | 2 |
 | 2 | 查询 g=0 | 6 | 2 |
 | 3 | 翻转 [2,4] | 取决于段交换 | 本地交换 |
 | 4 | 查询 g=1 | 更新 root.x1 | 更新 root.x0 |

 该痕迹表明翻转永远不会直接接触单个元素； 他们只交换汇总的异或贡献。 

### 第二个例子

 数组：`[5, 7]`细绳：`00`最初所有值都在 x0 中：

 | 步骤| 运营| x0 | x1 |
 | ---| ---| ---| ---|
 | 1 | 初始化| 5 ^ 7 = 2 | 5 ^ 7 = 2 0 |
 | 2 | 翻转 [1,2] | 0 | 2 |
 | 3 | 查询 g=0 | 0 | 2 |
 | 4 | 查询 g=1 | 2 | 0 |

 这证实了翻转段正确地交换了组成员身份而无需重新计算。

 ## 边缘情况

 一个关键的边缘情况是重复翻转相互抵消。 例如，将同一段翻转两次应该恢复原始分区。 在段树中，这是自然处理的，因为惰性标志会切换奇偶校验。 两次翻转再次将标志设置为 0，这意味着没有应用交换，因此 XOR 状态完全返回到其原始配置。 

另一种情况是查询翻转后变空的组。 由于空集上的 XOR 被定义为 0，因此线段树正确返回 0，因为相应的存储桶保持为空并且保留了 XOR 标识。 

最后一个微妙的情况是大量重叠更新。 即使许多翻转以任意模式重叠，每个节点也只存储翻转的奇偶校验，确保最终状态仅取决于它是否翻转了奇数次。
