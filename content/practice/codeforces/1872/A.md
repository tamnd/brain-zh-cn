 ## 解决方案
 ## 问题理解

 我们得到了两个装有实际水量的容器。 一开始于`a`，另一个与`b`。 我们还有一个最多可以转移的杯子`c`单次操作中的水单位。 在一次操作中，我们选择一个水源容器，取出一定量的水`c`，然后将其倒入另一个容器中。 

该过程不对称地改变两个值，但水的总量保持不变。 每次移动后，一艘船会减少一定量，另一艘船会增加相同量。 目标是使两个容器所含的量完全相同。 

由于总水量是固定的，唯一可能的最终状态是每个容器包含`(a + b) / 2`。 如果`a == b`，答案已经是零步了。 否则我们实际上是在尝试准确地转移`|a - b| / 2`单位水从较大的容器到较小的容器，最多使用尺寸转移`c`。 

限制非常小：`a, b, c ≤ 100`，直到`1000`测试用例。 这立即排除了对细粒度分数状态的任何模拟或对连续选择的搜索。 任何正确的解决方案都必须将过程简化为每个测试用例的直接算术计算。 

一个微妙的边缘情况是`c`足够大，可以一步转移全部差异。 另一个是当`c`非常小，需要很多部分传输。 总是准确转移的天真贪婪`c`仍然可以在这里工作，但前提是仔细处理所需转移的剩余部分。 

## 方法

 暴力解释将逐步模拟该过程。 在每一步中，我们都会选择较大的容器，转移一些量直至`c`，并尝试贪婪地减小差异。 如果我们总是转移`c`（或者如果较小，则剩余所需量），我们减少之间的绝对差`a`和`b`。 

这个模拟是正确的，因为每个操作都严格减少`|a - b|`除非它们已经相等。 然而，它的复杂性与移动次数成正比，在最坏的情况下约为`|a - b| / c`。 由于这里的值很小，这在技术上是可行的，但它隐藏了实际的结构：每次移动最多减少差异`c`，我们只关心达到零差异。 

关键的观察是我们永远不需要跟踪单个状态。 我们只追踪绝对差异`d = |a - b|`。 每一步最多可以将这种差异缩小`c`，并且由于我们总是可以最优地选择方向（从大到小），因此最优策略总是尽可能地减小差异。 这就把问题变成了一个简单的上限划分：多少块的大小`c`需要覆盖`d / 2`转移单位，但更清晰的是，我们根据每次移动的差异减少来进行推理。 

每一步最多减少差异`2c`从解决不平衡的角度来看，但更直接的是：转移`x`从大到小减少差异`2x`，所以最优的移动总是需要`x = min(c, remaining_needed/2)`有效。 这可以归结为一个简单的贪心计数：重复减去最多`c`从不平衡直至消失。 

因此答案是`ceil(|a - b| / (2c))`如果我们对称地对归约进行建模，但在标准 CF 解决方案中更清晰地导出，则可以简化为重复减少差异直到零，这等于`ceil(|a - b| / (2c))`。 在实践中，公认的公式是`ceil(|a - b| / (2c))`与每一步移动的事实相匹配`c`从一侧到另一侧。

 ## 算法演练

 1. 计算绝对差`d = |a - b|`。 这代表着必须通过转移消除的总体失衡。 
2.如果`d == 0`， 输出`0`立即，因为两艘船已经相等，不需要任何操作。 
3.每个操作最多可以移动`c`单位从一艘船到另一艘船，从而最佳地减少了单个方向上的不平衡。 
4. 由于每次移动都会减少不平衡`2 * x`在哪里`x ≤ c`，每次移动的最佳可能减少量是`2c`。 
5. 计算移动次数为最小整数`k`这样`k * 2c ≥ d`。 
6. 输出`ceil(d / (2c))`。 

### 为什么它有效

 系统的状态完全由差异描述`d`。 每次移动都会保留总质量和变化`d`减去两倍的转账金额。 因为我们总是选择较大的容器作为来源，所以我们总是减少`d`而不是增加它。 没有任何移动序列比始终使用允许的最大传输量更好`c`，因为任何较小的转移都会减少`d`速度更慢，并且永远不会创造补偿性的未来收益。 这使得该过程相当于重复减去`2c`从`d`直到它达到零，这会产生最佳步数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, c = map(int, input().split())
    d = abs(a - b)
    if d == 0:
        print(0)
    else:
        # each move can reduce difference by at most 2c
        print((d + 2 * c - 1) // (2 * c))
```实施首先读取每个测试用例并计算两个容器之间的绝对差异。 唯一重要的一步是认识到我们永远不需要显式地模拟传输； 整个过程简化为缩小这种差异。 

整数上限除法`(d + 2*c - 1) // (2*c)`编码了这样一个事实：我们将不平衡分为不同大小的块`2c`。 边缘情况`d == 0`单独处理以避免不必要的算术，尽管该公式也会返回零。 

## 工作示例

 ### 示例 1：`a = 3, b = 7, c = 2`我们计算`d = 4`。 

| 步骤| 差异 d | 行动| 减少| 新d|

 | 0 | 4 | 开始 | - | 4 |
 | 1 | 4 | 将 2 从 b 转移到 a | 4 → 0 | 0 |

 仅需要一次移动，因为一次大小转移`c`完全消除了不平衡。 This confirms that when`d ≤ 2c`，一次移动就足够了。 

### 示例 2：`a = 17, b = 4, c = 3`我们计算`d = 13`。 

| 步骤| 差异 d | 行动| 减少| 新d|

 | 0 | 13 | 开始 | - | 13 |

 这表明重复的最大传输贪婪地减少了差异，直到它消失。 最后一步是部分转移，这就是为什么天花板行为是必要的。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        a, b, c = map(int, input().split())
        d = abs(a - b)
        if d == 0:
            out.append("0")
        else:
            out.append(str((d + 2*c - 1) // (2*c)))
    return "\n".join(out)

 ## 边缘情况

 一种重要的边缘情况是差异小于杯子容量时。 例如`a = 1, b = 4, c = 10`给出`d = 3`。 该算法计算`(3 + 19) // 20 = 1`，这与我们可以一次转移所有所需的水而无需将其分开这一事实相匹配。 

另一种情况是当`a == b`。 这里计算出的差值为零，并且提前退出立即返回零移动。 如果没有这种检查，公式仍然会产生零，但显式分支使逻辑与不需要任何操作的解释一致。 

第三种情况是当`c = 1`，强制单位转移。 为了`a = 1, b = 100`，差值是 99，每一步最多减少 2。公式得出`(99 + 1) // 2 = 50`，这符合许多小调整的必要性，最佳地交替方向以精确地收敛到相等。
