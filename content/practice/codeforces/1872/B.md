 ## 解决方案
 ## 问题理解

 我们站在一维走廊的 1 号房间，想要前进到某个房间 k，然后返回到 1 号房间。每一步时间都会增加 1，因此第一次到达房间 x 需要 x−1 秒，返回的速度相同。 

有些房间设有陷阱。 每个陷阱都位于一个特定的房间中，并在从您第一次进入该房间开始计算的延迟后激活。 一旦陷阱激活，该房间就会永久不安全，你将无法再进入或离开它。 

关键的约束是，如果我们在时间 t 进入房间 d，那么从那一刻起 s 秒后，房间就会被封锁，所以在时间 t + s 是不安全的。 我们需要一个 k 值，以便向前行走到 k 和向后行走到 1 时避免在其激活时刻或之后进入任何房间。 

约束足够小，对于每个测试用例，我们可以对可能的限制陷阱进行 O(nk) 甚至 O(n log n) 推理，因为 n ≤ 100 且 t ≤ 1000。这表明每个测试用例可以通过直接计算路径上所有房间中最严格的陷阱来解决，而不是随着时间的推移尝试任何全局动态编程或模拟。 

当多个陷阱共享同一个房间时，会出现微妙的故障情况。 仅处理每个房间的第一个陷阱或错误地覆盖值的简单方法可能会低估房间变得不安全的时间。 另一个常见问题是混合前向和后向时序：回程比前程更晚进入房间 i，因此必须根据相同的激活阈值检查两个方向。 

## 方法

 蛮力方法会尝试 k 的所有可能值。 对于每个 k，我们一步步模拟旅程，跟踪时间并检查我们是否在陷阱激活后进入过房间。 这是正确的，因为它直接遵循规则，但每次模拟的成本为 O(k)，并且对所有 k 到 200 执行此操作使得每个测试用例的成本为 O(n^2)。 这在孤立的情况下是可以接受的，但变得不必要，因为可行性条件可以在每个房间本地表达。 

关键的观察是，每个房间对我们能走多远都有一个独立的上限。 如果我们到达房间 d，我们必须确保在其陷阱在向前和向后通过时激活之前到达。 由于到达时间是确定性的，因此每个陷阱都给出 k ≤ f(d, s) 形式的约束。 对所有陷阱取最小约束可以直接给出答案。 

蛮力之所以有效，是因为它明确地检查每个 k 的有效性，但当我们注意到有效性仅取决于所有陷阱中最严格的约束，而不取决于它们之间的相互作用时，它就会失败。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力模拟 | O(nk) | O(nk) | O(1) | O(1) | 可以接受但没有必要 |
 | 约束聚合 | O(n) | O(n) | 已接受 |

 ## 算法演练

 对于每个测试用例，我们将每个陷阱转换为对最大可达 k 的限制。

1. 对于房间 d 的陷阱，延迟为 s，计算在前进的旅程中我们可以进入该房间的最新安全时刻。 由于向前到达时间是 d−1，所以我们必须有 d−1 < s，否则就已经太晚了。 这通过 d 间接给出了对 k 的前向约束。 
2. 在回程中，如果我们到达 k 并返回，我们将在时间 2k − d + 1 重新进入 d 房间。这也必须严格小于 s。 
3. 结合两个条件得出该陷阱的 k 上限。 前向和后向约束中更严格的一个决定了该陷阱所产生的实际限制。 
4. 维护一个初始化为非常大的值的全局答案，并为每个陷阱计算其允许的最大 k，用最小值更新答案。 
5. 处理完所有陷阱后，答案是满足所有约束的最大 k。 

这样做的原因是每个陷阱都独立地限制我们可以安全地延伸路径的距离。 由于路径是线性且确定性的，因此陷阱之间不存在组合依赖性，只有逐点时间约束。 所有约束的最小值给出最大的可行 k。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        d = []
        s = []
        for _ in range(n):
            x, y = map(int, input().split())
            d.append(x)
            s.append(y)

        ans = 10**18

        for i in range(n):
            di = d[i]
            si = s[i]

            # forward constraint: arrive at time di-1
            # must satisfy di-1 < si
            if di - 1 >= si:
                ans = 0
                continue

            # backward constraint:
            # time when returning and entering di is (2k - di + 1)
            # must satisfy 2k - di + 1 < si
            # => k < (si + di - 1) / 2
            limit = (si + di - 2) // 2

            ans = min(ans, limit)

        print(max(1, ans))

if __name__ == "__main__":
    solve()
```该解决方案针对每个陷阱计算该陷阱允许的最大 k，然后取所有陷阱中的最小值。 前向条件作为硬不可行性案例而被尽早检查。 后向条件转化为从返回时间表达式导出的 k 的简单不等式。 

整数除法必须小心，因为约束很严格：我们要求到达时间严格小于激活时间。 

## 工作示例

 考虑一个简单的情况，房间 2 有一个陷阱，s = 2。向前到达房间 2 发生在时间 1，这仍然是安全的，但返回房间 1 在时间 3 再次经过房间 2，这违反了约束，因此 k 上限为 2。 

| 陷阱| Forward condition | Backward limit | Resulting k cap |
 | --- | --- | --- | --- |
 | (2, 2) | 好的 | tight | 2 |

 现在考虑多个陷阱，其中一个陷阱很早，另一个陷阱很远。 答案总是由最小的上限决定，这表明只有最严格的约束才重要。

 ## 边缘情况

 当陷阱恰好在我们回程中重新进入其房间时激活时，就会出现一个关键的边缘情况。 该算法可以正确处理此问题，因为它使用严格的不等式转换为下限除法界限，确保拒绝等式。 另一种边缘情况是陷阱已经阻止了前进的旅程； 在这种情况下，我们立即限制答案，因为在考虑返回路径之前任何更大的 k 都会违反安全性。
