 ## 解决方案
 ## 问题理解

 给定一个正整数序列，并且允许我们执行一次转换：选择一个连续的段，将其压缩为等于该段中所有元素的乘积的单个数字，然后用该单个值替换该段。 该段之外的所有内容都保持不变。 最终目标是选择段，使得结果数组具有最大可能的总和。 

该操作的关键效果是元素块作为单独的值或作为单个产品贡献。 由于所有数字均为正数，因此如果乘积与其元素之和相比足够大，则替换段会增加其贡献，否则会减少其贡献。 任务是找到这种权衡最有利的部分。 

这些约束意味着测试用例的总数组长度最多为 2×10^5，因此每个测试用例的任何解决方案都必须是线性或接近线性的。 在最差分布中，对每个测试用例的所有子阵列进行二次扫描将达到大约 10^10 次操作，这远远超出了限制。 

当数组包含很多时，就会出现一个微妙的极端情况。 在这种情况下，用乘积替换一段 1 没有任何作用，因为和和乘积都是 1。这使得许多段等效。 另一个极端情况是当任何元素大于 1 并且被 1 包围时，因为将其与 1 合并可能会也可能不会提高总和​​，具体取决于吸收了多少个元素。 

## 方法

 直接方法检查每个可能的部分。 对于每对 l 和 r，计算 a[l..r] 的乘积，计算替换后的结果数组总和，并跟踪最佳值。 这在概念上是有效的，因为操作是完全定义的并且只有 O(n^2) 段。 然而，即使使用前缀乘积或对数，候选的数量仍然是二次的，这对于 n 高达 2×10^5 来说太慢了。 

关键的观察结果是，几乎所有等于 1 的元素在乘法下都是中性的，但当它们分开时，它们对总和有正贡献。 合并唯一有帮助的时候是当我们包含至少一个大于 1 的元素时，因为只有这些元素才能有意义地改变产品。 这将问题从“选择任何分段”转变为“决定如何处理围绕较大值的分段”。 

如果我们看看合并段的效果，替换只包含段的块是没有用的。 替换仅包含一个非一元素的块也是没有用的，除非它以一种改进边缘情况下的最终总和结构的方式合并周围的元素。 最佳策略最终会崩溃为选择一个包含所有非单一元素的细分，因为围绕它们的任何额外划分都不会提高产品效益。 

因此，解决方案简化为找到包含严格大于 1 的所有元素的最小区间。任何最佳答案都是这样的区间，并且如果数组仅包含元素，则任何单个位置都是最佳的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^3) 或 O(n^2) | O(1)-O(n) | O(1)-O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从左到右扫描数组，同时跟踪值大于 1 的第一个位置。这定义了左边界候选。 
2. 继续扫描找到值大于1的最后一个位置。这定义了正确的边界候选。 
3. 如果不存在大于 1 的值，则返回任何单个索引，例如 (1, 1)，因为每个元素都是 1 并且任何操作都会产生相同的结果。 
4. 否则，输出第一次出现到最后一次出现大于1的值的间隔。

这种构造足够的原因是，任何等于 1 的元素除了按 1 缩放外都不会改变乘积，但如果将其留在合并段之外，则会增加数组总和。 因此，在合并段中包含不必要的部分只会减少最终的总和，因为它们不再单独贡献。 

### 为什么它有效

 该变换用其乘积来替换段。 任何等于 1 的元素对乘法的影响为中性，但在单独放置时会对总和贡献 +1。 将其从数组中删除，总和正好减少 1，而将其包含在乘积中不会使乘积增加到中性缩放效应之外。 因此，除非有必要连接非 1 元素，否则任何最佳分段都不会包含 1，并且覆盖所有大于 1 的元素的最小间隔保留了所有有益的乘法，同时避免了不必要的加法贡献损失。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    l = -1
    r = -1
    
    for i in range(n):
        if a[i] != 1:
            if l == -1:
                l = i
            r = i
    
    if l == -1:
        print(1, 1)
    else:
        print(l + 1, r + 1)
```该实现对每个测试用例执行一次通过。 我们记录数组不等于 1 的第一个和最后一个索引。这些索引定义了我们压缩的段。 

关键的实现细节是在一次扫描中维护两个端点。 当我们第一次看到非一个值时，我们修复左边界。 每个后续的非一都会更新右边界。 这避免了任何额外的遍或预处理的需要。 

所有元素均为 1 的边缘情况是通过检查是否设置过左边界来显式处理的。 

## 工作示例

 考虑输入数组 [1, 3, 1, 3]。 

| 我| 一个[我] | 我| r |
 | ---| ---| ---| ---|
 | 0 | 1 | -1 | -1 |
 | 1 | 3 | 1 | 1 |
 | 2 | 1 | 1 | 1 |
 | 3 | 3 | 1 | 3 |

 该算法选择段 (2, 4)。 这包括两个非一个元素，并将所有周围的元素保留在外面，以最大限度地提高对总和的贡献。 

现在考虑 [2, 1, 2, 1, 1, 3]。 

| 我| 一个[我] | 我| r |
 | ---| ---| ---| ---|
 | 0 | 2 | 0 | 0 |
 | 1 | 1 | 0 | 0 |
 | 2 | 2 | 0 | 2 |
 | 3 | 1 | 0 | 2 |
 | 4 | 1 | 0 | 2 |
 | 5 | 3 | 0 | 5 |

 所选线段变为 (1, 6)。 这会收集所有非一元素，以便它们的乘积最大化，同时保留所有外部元素的加性贡献，因为它们位于跨度内，所以在这里是不可能的，但不存在更好的分割，因为分裂会隔离非一贡献并减少乘法增益。

 ## 边缘情况

 对于完全由 [1, 1, 1] 等元素组成的数组，扫描永远不会找到任何不同于 1 的元素，因此两个边界都保持未设置状态。 该算法直接返回 (1, 1)，这将总和保留为 3，因为用其乘积替换任何段不会改变总数。 

对于像 [2, 1, 1, 3] 这样的情况，第一个非一在索引 0 处设置 l，最后一个非一在索引 3 处设置 r。输出 (1, 4) 合并所有内容。 任何选择较小段的尝试都将排除 2 或 3，从而减少结果乘积，从而与全跨度合并相比降低最终总和。
