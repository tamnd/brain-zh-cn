 ## 解决方案
 ## 问题理解

 我们得到了几个由字母组成的字符串`'a'`通过`'j'`。 最初，这些字符串是十进制数字。 恶作剧者用一个唯一的字母替换了每个数字，在这十个数字之间创建了一一对应的关系`0...9`和十个字母`a...j`。 

相同的字母总是代表相同的数字，不同的字母代表不同的数字。 我们的任务是重建这样的映射，以便每个结果数字都是有效的，这意味着没有数字以数字开头`0`，并且所有重构数的总和尽可能小。 

关键的观察是我们没有独立地重建个体数字。 数字到字母的单一分配必须在所有字符串中全局有效。 

字符串长度方面的限制很小。 最多有 1000 个字符串，每个字符串的长度最多为 6，因此字符位置总数最多为 6000 个。这意味着我们有能力处理每个字符并计算位置贡献。 不同字母的数量固定为 10 个，这个数量很小。 任何涉及对这十个字母进行排序或分配的算法本质上都是恒定时间。 

一个诱人但危险的错误是独立对待每个事件。 分配给字母的数字会影响该字母出现的每个位置。 例如：```
2
aa
a
```如果`a`被分配的数字`9`，总和是`99 + 9 = 108`。 如果`a`被分配的数字`1`，总和是`11 + 1 = 12`。 每个字母的出现都会同时产生影响，因此我们必须汇总每个字母的所有位置影响。 

另一个微妙的问题是前导零限制。 考虑：```
2
ab
ac
```信`a`显示为多位数字的第一个字符，因此分配数字`0`到`a`是非法的。 简单给出数字的贪心策略`0`不检查此约束而将最不有价值的字母转换为最不有价值的字母可能会产生无效的重建。 

当字母从未作为前导字符出现时，就会出现第三种边缘情况。 这样的字母是唯一可以接收数字的字母类型`0`。 该语句保证有效的赋值始终存在，但算法仍然必须选择正确的零候选。 

例如：```
1
ab
```这里`a`不能为零，但是`b`能。 分配`b = 0`和`a = 1`给出最小有效数`10`。 

## 方法

 强力解决方案将枚举所有可能的数字到字母的分配。 由于有十个字母和十个数字，所以有`10! = 3,628,800`双射。 对于每项作业，我们可以评估结果总和并保留最小有效总和。 

暴力方法是正确的，因为它检查每个可能的映射。 问题是工作量。 即使评估映射的成本非常低，但对于一秒的限制来说，数百万次分配已经太多了。 

为了找到更好的解决方案，我们应该检查总和是如何形成的。 

假设一个字母在单位位置出现了五次。 分配数字`7`这封信的贡献`5 × 7`到最后的总和。 如果同一个字母在百位中出现两次，则有贡献`2 × 100 × 7`。 

一封信的所有贡献可以组合成一个系数：$$\text{contribution} = \text{digit(letter)} \times \text{weight(letter)}$$在哪里`weight(letter)`是该字母出现的所有位值的总和。 

总和变为$$\sum \text{digit(letter)} \times \text{weight(letter)}$$现在问题就清楚多了。 我们有十个权重，必须分配数字`0...9`给他们。 为了最小化加权和，较小的数字应分配较小的权重，较大的数字应分配较大的权重。 这是一个标准的交换论证。 

唯一的麻烦是数字`0`。 它不能分配给作为多位数字的前导字符出现的字母。 在所有符合零的字母中，我们应该选择权重最小的一个，因为零完全消除了该权重。 

修复零字母后，其余九个字母接收数字`1...9`按重量升序排列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(10!·T) | O(10!·T) | O(1) | O(1) | 太慢了 |
 | 最佳| O(T + 10 log 10) | O(T + 10 log 10) | O(10) | 已接受 |

 这里`T`是所有字符串的字符总数。 

## 算法演练

 1. 创建数组`weight[10]`，每个字母一个条目。 
2. 对于每个字符串，从右向左扫描。 最右边的位置有贡献`1`，下一个贡献`10`， 然后`100`， 等等。 
3. 每当字母出现在有位值的位置时`p`， 添加`p`到那封信的重量。 
4. 记录哪些字母禁止变为零。 禁止任何作为长度大于 1 的字符串的第一个字符出现的字母。 
5. 在所有不被禁止的字母中，选择权重最小的一个。 分配数字`0`到这封信。 
6. 收集剩余的 9 个字母，并按重量升序排列。 
7. 分配数字`1, 2, ..., 9`按照排序顺序对这些字母进行排序。 
8. 将最终答案计算为以下总和`digit(letter) × weight(letter)`超过所有十个字母。 

### 为什么它有效

 字母的重量完全与数字分配无关。 一旦权重已知，最终的总和就是加权线性表达式。 

在所有允许接收零的字母中，将零分配给最小的权重始终是最佳的。 如果将零分配给较大的权重，而较小的合格权重收到正数，则交换这些分配将减少总和。 

修复零字母后，只剩下数字`1...9`保持。 假设两个字母有重量`w1 ≤ w2`但接收数字`d1 > d2`。 交换他们的数字会改变总和$$(w1d2+w2d1)-(w1d1+w2d2) =(w2-w1)(d1-d2)\ge 0$$所以原来的分配不可能比交换后的分配更好。 重复应用这个论点表明权重和数字必须以相同的方式排序。 因此按重量对剩余字母进行排序并分配数字`1...9`按递增顺序产生可能的最小总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    weight = [0] * 10
    leading = [False] * 10

    for _ in range(n):
        s = input().strip()

        if len(s) > 1:
            leading[ord(s[0]) - ord('a')] = True

        place = 1
        for ch in reversed(s):
            weight[ord(ch) - ord('a')] += place
            place *= 10

    zero_letter = -1
    best_weight = None

    for i in range(10):
        if not leading[i]:
            if best_weight is None or weight[i] < best_weight:
                best_weight = weight[i]
                zero_letter = i

    letters = [i for i in range(10) if i != zero_letter]
    letters.sort(key=lambda x: weight[x])

    digit = [0] * 10

    for d, letter in enumerate(letters, start=1):
        digit[letter] = d

    ans = 0
    for i in range(10):
        ans += digit[i] * weight[i]

    print(ans)

solve()
```第一部分计算每个字母的位置权重。 我们不是直接重建数字，而是累积每个字母对指定数字单位的最终总和的贡献程度。 

这`leading`数组跟踪哪些字母被禁止接收零。 只有多位字符串的第一个字符很重要。 一位数字在恢复后可以合法地为零，因为它没有前导零。 

的选择`zero_letter`是最微妙的一步。 我们仅在未标记为前导的字母中进行搜索，并选择最小权重。 这消除了尽可能多的不必要的贡献。 

排除零字母后，剩下的字母按权重排序。 分配数字`1...9`按此顺序实现交换参数最优。 

最大可能的权重完全在 Python 的整数能力范围内，但使用 Python 整数会自动避免任何溢出问题。

 ## 边缘情况

 考虑：```
1
ab
```重量是`a=10`,`b=1`。 信`a`是主角并且不能接收零。 该算法仅在非前导字母中搜索并选择`b`对于数字`0`。 结果分配给出了价值`10`，这是最小的有效重构。 

现在考虑：```
3
a
a
a
```只出现一个字母。 它的重量是`3`。 其他所有字母都有重量`0`并且有资格为零。 该算法将零分配给未使用的字母和数字`1`到`a`，产生答案`3`。 分配零给`a`会给出总和`0`，但这会使原来的正数无效。 

最后考虑：```
2
ab
ac
```重量是`a=20`,`b=1`,`c=1`。 信`a`禁止接收零。 该算法选择一个未使用的具有权重的非前导字母`0`对于数字`0`，然后将最小的正数字分配给权重为 1 的字母，将最大的数字分配给`a`。 自动遵守前导零约束，同时仍最小化总和。
