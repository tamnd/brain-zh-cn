 ## 解决方案
 ## 问题理解

 我们被要求将给定的整数序列转换为“好的”序列。 如果相同数字的所有出现都出现在连续的块中，则序列是好的。 例如，`[3, 3, 1, 1, 2]`很好，但是`[3, 1, 3]`不是因为`3`s 被分割为`1`。 目标是计算实现此属性所需更改的最小元素数，附加规则是如果我们更改任何值元素`x`进入`y`，我们必须改变所有元素等于`x`到`y`。 我们被给予`n`这个简单版本中的整数和零更新。 输出是表示最小更改数量的单个整数。 

限制因素很重要：`n`最多可达 200,000。 尝试每种可能的序列转换的简单解决方案会太慢，因为它可能需要检查指数数量的序列。 我们需要接近线性或线性时间的东西。 可能导致幼稚实现失败的边缘情况包括值重复交替的序列，例如，`[1, 2, 1, 2, 1]`，或所有值都已相同的序列。 另一个微妙之处是，更改某个数字的一​​个出现会迫使所有其他出现发生变化，因此我们不能独立对待每个位置。 

## 方法

 暴力方法会考虑每个可能的数字块分配，计算每个数字需要多少次更改。 从概念上讲，这是可行的，因为对于每个数字，我们可以决定它应该占据哪个块，但实际上，它是 O(n^2) 或更糟，因为对于每个数字，我们将扫描所有位置。 为了`n = 2e5`，这是不可行的。 

关键的见解是我们只需要跟踪数字的“块”，而不是单个位置。 让我们将序列压缩为连续的运行或块。 例如，`[3, 3, 1, 3, 2, 1, 2]`变成`[3, 1, 3, 2, 1, 2]`就块而言。 然后，对于每个唯一的数字，我们可以计算它形成了多少个单独的块。 该数字的最小更改次数是块总数减一，因为将所有块合并为一个连续的块需要更改中间块中的所有元素。 总体难度是我们必须改变的最小元素数量，它等于块总数减去可以保留的相同值块的最大数量。 这将问题减少到对每个值的块进行计数，这可以在单遍中完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将输入序列压缩为连续的块。 迭代数组，跟踪前一个元素。 每当当前元素与前一个元素不同时，它就会开始一个新块。 这给出了按出现顺序排列的块列表。 
2. 计算每个唯一值的块频率。 初始化一个字典，将每个数字映射到它占用的块数。 遍历块序列，递增每个块的计数器。 
3. 找出块数最多的数字。 让`max_blocks`是最高的块数。 这个数字是我们基本保持不变的数字，因为它需要的更改最少。 所有其他数字的块必须合并到该结构中，这需要更改中间元素。 
4. 计算难度为区块总数减去`max_blocks`。 不属于主导数字的每个块至少贡献一项所需的更改。 
5. 打印计算出的难度。 

工作原理：通过压缩成块并按值对它们进行计数，我们捕获了序列中的所有不连续性。 最小更改数量取决于必须消除或合并的块数。 选择具有最大数量的块的数量可以确保我们最小化更改，因为更改更少的块需要更少的元素修改。 这种贪婪策略是最优的，因为每个不属于所选数字的块都会强制改变，并且没有任何序列可以通过更少的修改变得更好。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
a = list(map(int, input().split()))

# Step 1: compress into blocks
blocks = []
prev = None
for x in a:
    if x != prev:
        blocks.append(x)
        prev = x

# Step 2: count blocks per value
from collections import defaultdict
block_count = defaultdict(int)
for b in blocks:
    block_count[b] += 1

# Step 3: find max block count
max_blocks = max(block_count.values())

# Step 4: compute difficulty
difficulty = len(blocks) - max_blocks
print(difficulty)
```在此解决方案中，我们首先压缩序列以识别实际的块结构。 使用字典，我们计算每个数字占用了多少个块。 占据最多块的数字需要最少的更改。 最终的难度是区块总数减去这个最大值。 

微妙的实现点包括当连续元素不同时正确识别新块、正确更新前一个元素以及使用字典有效地跟踪块计数。 忘记压缩成块会导致计算过多并给出错误的答案。
