 ## 解决方案
 ## 问题理解

 我们得到了一个整数列表，我们希望将它们分成尽可能少的组。 每个组都有一个结构约束：如果您查看该组内的最小数字，则分配给同一组的所有其他数字都必须能被该最小数字整除。 

您可以将每个组视为由其最小元素“锚定”。 一旦你选择了这个最小值，组中的其他所有内容都必须是它的倍数。 任务是将每个数字分配给某个组，同时最小化创建的组数。 

值最多为 100 的约束显着改变了问题的性质。 我们不需要大状态上的复杂图或 DP，而是可以直接推理小整数之间的频率和整除结构。 任何尝试在没有全局视图的情况下显式枚举分区或贪婪地分配元素的解决方案都有可能错过最佳分组，特别是因为相同的值可能会出现多次并且必须一致地处理。 

当数字共享除数但不直接在链中时，就会出现天真的推理的微妙失败情况。 例如，在`[6, 10, 15]`，贪心方法可能会尝试基于部分兼容性来组合 6 和 10 或 10 和 15，但它们都不能共享一个组，除非所有元素都是所选最小值的倍数。 由于没有任何对共享将两者分开的有效共同最小值，因此正确答案是 3 组。 

另一个微妙的情况是重复和除数重用。 在`[2, 4, 8, 3, 9]`，人们很容易认为我们可以为多个不相关的链“重用”一个组，但每个组的最小强制严格的可分性，因此我们必须仔细决定哪些数字充当锚点。 

## 方法

 暴力方法会尝试将每个元素分配到几个组中的一组并检查有效性。 对于每个作业，我们将验证每个组中的所有数字都可以被该组的最小元素整除。 这导致了指数搜索空间，因为每个元素都有多个组选择，并且我们事先不知道最佳组数。 即使进行剪枝，n 个元素的分区数量增长也太快，因为 n 达到 100。 

关键的结构观察是组成员资格完全由所选的最小值决定。 如果数字 x 是一组中的最小值，则该组中的每个元素都必须是 x 的倍数。 这意味着对于每个可能的值x，我们可以考虑它是否应该充当组代表，然后将其所有倍数分配给该组（如果它们尚未分配给其他地方）。 

一旦我们以这种方式解释问题，目标就变成选择一组“锚”，使得每个数字都属于一个锚的组，并且每个锚只能覆盖可被自身整除的数字。 最佳策略是从小到大处理数字，每当我们遇到尚未分配到任何较早组的数字时，它必须开始一个新组。 然后我们将其所有倍数标记为该组所涵盖的。 

这是有效的，因为较小的数字总是更好的锚：它们划分更多的数字，因此创建更灵活的组。 较大的数字不能成为较小数字的有用锚，因此延迟决策只会面临失去最佳分组的风险。

 ## 算法演练

 我们使用数组或频率结构来跟踪哪些值仍未分配。 

1.初始化布尔数组`used`超过取值范围。 这会跟踪号码是否已分配给某个组。 
2. 迭代从 1 到输入中的最大值的可能值。 这种排序确保我们始终从最小到最大考虑潜在的组锚。 
3.当我们遇到一个值时`x`出现在输入中并且尚未标记为已使用，我们决定`x`starts a new group. 这种选择是被迫的，因为不存在可以有效锚定的更早的较小除数`x`。 
4.一次`x`被选为组最小值，我们标记每个倍数`x`如所用。 这表示分配所有可被整除的数字`x`进入这个组。 这是安全的原因是每个倍数`x`满足可分性约束`x`。 
5. 继续向上扫描，只要我们发现数组中出现未使用的数字，就重复该过程。 

最终的答案是我们开始一个新组的次数。 

正确性取决于以下不变量：每当我们以值 x 开始一个组时，每个小于 x 的数字都已完全处理和分配，并且 x 是最小的未分配值。 这保证了 x 不能被放入任何较早的组中，因为任何较早的组都会有一个较小的不能整除 x 的最小值。 因此，在 x 处开始一个新组是不可避免的，并且贪婪地覆盖所有倍数可以最大化覆盖范围，而不会出现无效分配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    maxv = max(a)
    freq = [0] * (maxv + 1)
    
    for x in a:
        freq[x] += 1

    used = [False] * (maxv + 1)
    groups = 0

    for x in range(1, maxv + 1):
        if freq[x] > 0 and not used[x]:
            groups += 1
            for multiple in range(x, maxv + 1, x):
                used[multiple] = True

    print(groups)

if __name__ == "__main__":
    solve()
```该解决方案首先将输入压缩到频率数组中，以便我们可以快速测试某个值是否存在。 这`used`数组跟踪一个值是否已经被吸收到某个较早的组中。 

循环结束`x`确保我们始终按升序处理潜在的团队领导者。 当我们选择一个新的领导者时，我们立即标记其所有倍数，这可以防止它们稍后形成冗余组。 

一个常见的错误是直接迭代输入数组而不是值范围。 这破坏了除数结构，因为分组取决于数字关系，而不是输入顺序。

 ## 边缘情况

 一个关键的边缘情况是所有数字都是成对互质的，例如`[7, 11, 13]`。 该算法在每个值处启动一个新组，因为没有一个组可以划分另一个组，从而产生三个组，这是最佳的，因为不可能进行分组。 

另一种情况是完全嵌套的除数链，例如`[2, 4, 8, 16]`。 该算法从 2 开始，标记所有倍数，并以一组结束。 这表明早期锚定正确地将长链折叠成单个组。 

第三种情况涉及重复值，例如`[3, 3, 6, 6, 12]`。 前 3 个成为锚，所有其他都立即被吸收，确认重复不会增加组数。
