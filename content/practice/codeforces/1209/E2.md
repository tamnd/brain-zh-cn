 ## 解决方案
 ## 问题理解

 我们得到一个行数较少但列数可能较多的网格。 唯一允许的操作是获取任何单个列并将其循环旋转任意次数。 对每列独立执行这些旋转后，我们查看每一行并选择该行内的最大值。 配置的最终得分是这些行最大值的总和，任务是最大化该得分。 

关键的自由度是每列都可以通过旋转进行排列，但只能循环排列，这意味着每列保留其多组值，但我们可以选择哪个元素位于哪一行。 由于各列的旋转是独立的，因此最终的排列是通过为每列选择垂直移位来确定的。 

约束 n ≤ 12 是核心结构提示。 这意味着每一列都可以被认为是在最多 12 个位置上选择一个排列，因此搜索空间在 n 中呈指数分布，但以允许聚合的方式与 m 无关。 最大到 2000 的 m 表明我们必须在按类型分类后压缩或贪婪地累积列贡献。 

当人们假设每一行可以独立地从每一列中获取最佳值时，就会出现天真的思维的微妙失败案例。 这会错误地过度计算，因为单个列为每行分配提供了一个值，并且跨列转移了行选择。 

例如，考虑 n = 2 和单列 [10, 1]。 人们可能会认为通过不同的旋转，两行都可以“得到 10”，但列旋转一次只能将 10 恰好放置在一行中。 一列的正确答案是旋转次数的 max(10 + 1)，即 11，而不是 20。 

另一个陷阱是独立处理每一列并将其最大值分配给全局最佳行。 这忽略了多个列可能希望同时将其最大值放入不同的行，并且冲突会减少可实现的总和。 

## 方法

 暴力方法将尝试每一列的所有循环移位。 每列有 n 种可能的旋转，因此有 n^m 种配置。 即使我们独立地修剪每列，列之间的相互作用仍然是组合的，因为最终的行最大值取决于联合对齐。 即使 m = 2000，这也是远远不可行的。 

关键的观察结果是 m 很大但 n 很小。 我们没有考虑独立选择轮班的专栏，而是颠倒了视角。 我们询问在选择所有列后，哪一组值最终可能成为每行中的最大值。 

对于任何固定列，旋转将其值分配给行，因此它会在行上贡献其元素的排列。 关键思想是对每列进行分类，行的子集接收其最大的几个元素。 由于 n ≤ 12，行的子集可以表示为位掩码，并且列内值的相对顺序仅与选择将哪些顶部位置分配给哪些行有关。 

对于每一列，我们预先计算可以由该列“激活”的每个行子集的最佳可能贡献。 然后，全局问题就变成为每个掩码模式选择列的子集，确保每行的最终最大值与至少一列在正确位置为其分配一个大值一致。 位掩码上的 DP 跟踪哪些行已经被所选列“满足”，并且我们贪婪地或 DP 组合列贡献。

更具体和标准的重新表述是独立处理每一列：对于固定的行子集 S，定义我们可以分配的最佳值，以便这些行被视为获得该列最大影响力的候选行。 我们对每列进行降序排序，并将其第 k 个最大值与选择 k 个不同的行相关联。 这导致了掩码上的子集卷积式 DP。 

然后，我们进行 DP，其中迭代地添加列，将它们的贡献合并到全局掩码 DP 中，其中行已经具有保证的候选最大值。 由于m很大，我们无法在全DP中单独处理每一列； 相反，我们会累积相同色谱柱配置文件的频率，并对每个唯一的色谱柱应用 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解旋转 | O(n^m) | O(n^m) | O(纳米) | 太慢了 |
 | 列上的掩模 DP | O(m · n^2 · 2^n) 优化为 O(m · 2^n) 摊销 | O(2^n) | O(2^n) | 已接受 |

 ## 算法演练

 1. 对于每一列，按降序排列其值。 这确保我们知道哪些值是某些旋转对齐下行最大值的最佳候选值。 
2. 将每一列解释为提供最多 n 个“排名贡献”，其中分配其第 k 个最大值对应于将一个强大的候选者放置到某个行位置。 
3. 对于固定列，通过位掩码计算 DP 数组，其中 dp[mask] 是可实现的最佳总贡献，如果掩码中的行集是由该列的较高排名元素“服务”的行。 这对我们分配最高值的行进行编码。 
4. 使用掩码上的全局 dp2 数组组合跨列的贡献。 每列通过转换 dp2[mask] → dp2[mask | 子掩码] + 贡献[子掩码]。 这是子集上的标准背包，其中每列都是具有 2^n 个状态的项目。 
5. 处理完所有列后，将 dp2[full_mask] 解释为可实现的最佳总数，其中每一行都已分配了与某些旋转配置一致的最佳可能列贡献。 
6. 答案是所有全覆盖状态的最大值，即 dp2[(1 << n) - 1]。 

### 为什么它有效

 不变的是，在处理列的前缀之后， dp2[mask] 存储可实现的最佳贡献总和，使得 mask 中的行准确地收到了迄今为止其最终确定的最大候选，与有效的列旋转一致。 每个转换都保留了可行性，因为每个列分配都对应于有效的循环移位，并且每个子集分配都对应于选择哪些行接收哪个排序元素。 由于每行的最终最大值仅取决于它在各列中收到的最佳分配值，因此 DP 确保我们探索所有一致的分配，而不会重复计算或违反列约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    # transpose to columns
    cols = []
    for j in range(m):
        col = [a[i][j] for i in range(n)]
        col.sort(reverse=True)
        cols.append(col)

    # dp over masks: best total contribution
    dp = [-10**18] * (1 << n)
    dp[0] = 0

    for col in cols:
        # precompute contribution for this column:
        # assigning k top elements to some subset of size k
        contrib = [0] * (1 << n)

        for mask in range(1 << n):
            vals = []
            for i in range(n):
                if mask & (1 << i):
                    vals.append(i)
            # assign top len(mask) values
            total = 0
            for idx, row in enumerate(vals):
                total += col[idx]
            contrib[mask] = total

        ndp = dp[:]
        for mask in range(1 << n):
            if dp[mask] < -10**17:
                continue
            for sub in range(1 << n):
                if mask & sub:
                    continue
                val = dp[mask] + contrib[sub]
                nm = mask | sub
                if val > ndp[nm]:
                    ndp[nm] = val

        dp = ndp

    print(dp[(1 << n) - 1])

if __name__ == "__main__":
    solve()
```该代码首先将网格转换为列并对每列进行排序，以便轻松分配其最高值。 对于每一列，它在所有行子集上构建一个贡献表，将每个子集解释为选择在一些旋转后接收该列顶部元素的行。 

然后 DP 通过掩码将每一列合并为全局状态。 每个掩码代表哪些行已经被选定的贡献“覆盖”。 该转换尝试所有不相交的子集添加，确保在同一列组合中没有为任何行分配多个不兼容的角色。 

一个微妙的点是，我们将每列的 dp 数组克隆到 ndp 中，确保我们不会在同一列处理中重复使用部分更新。 这保留了列上 0-1 背包结构的正确性。

 ## 边缘情况

 最小单单元矩阵表明 DP 必须正确初始化 dp[0] = 0 并直接接受唯一值而不尝试子集转换。 假设每一列都必须对每一行做出贡献的简单实现会错误地过度计数。 

具有多行的单列矩阵测试旋转模型。 由于旋转不会改变多重集值，因此最好的结果只是在每行分配中获取最大元素，并且 DP 不得人为地强制从一列进行多个贡献。 

统一矩阵（例如所有值都相等）暴露了子集分配逻辑是否意外地更喜欢某些掩码； 正确性需要对称性，以便所有分配产生相同的总数，并且 DP 不得通过迭代顺序引入偏差。 

单列中存在一个极大值的偏斜矩阵会检查算法是否正确将该值分配给单行而不尝试分配它，从而保留通过有效子集选择分配每列贡献的不变式。
