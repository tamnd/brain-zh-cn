 ## 解决方案
 ## 问题理解

 我们得到了一系列小吃类型和一群客人。 每种零食类型只出现一次，因此有$n$标记不同的项目$1$到$n$。 每位客人都有两种喜欢的小吃类型。 客人按照选定的顺序到达，当客人到达时，他们会吃完他们最喜欢的两种类型的剩余零食。 如果他们最喜欢的两种小吃已经被之前的客人吃过，那么该客人就会不高兴地离开。 

任务是安排客人的来访顺序，使不满意的客人数量尽可能少。 

重新解释此过程的一个有用方法是将每种零食类型视为一个节点。 每个客人都是连接他们关心的两种零食类型的无向边。 当访客到达时，他们“删除”两个端点，从系统中删除这些节点。 任何后来接触已删除节点的来宾可能仍会使用另一个端点（如果该端点仍然存在），但如果两个端点都已被删除，则该来宾将贡献答案。 

输入大小达到$10^5$节点和$10^5$边缘。 这立即排除了对客人订单的任何基于排列或阶乘的推理。 即使是所有对的二次图算法也太慢了。 我们通常需要一些本质上线性或接近线性的东西$O(n + k)$或者$O(k \log n)$。 

当多位客人共享同一种零食时，就会出现微妙的边缘情况。 例如，如果两位客人都喜欢$(1,2)$，如果第一个在它之前处理，第二个总是不满意，但排序仍然会影响这些顶点相对于其他边是早还是晚消失。 另一个边缘情况是当图已经是树或森林时，结构更简单，而当它包含循环时，决策会相互作用。 

关键的困难在于，删除一位客人可能会断开其他客人未来的用处，因此贪婪的本地订购显然并不安全。 

## 方法

 蛮力方法会尝试客人的所有排列，模拟就餐过程，并计算不满意的客人。 这是正确的，但完全不可行，因为它需要$k!$模拟，并且每个模拟本身的成本$O(n + k)$，导致指数运行时间。 

重要的观察是，客人只能通过零食类型形成的图表的连接结构来影响。 当客人吃掉两个端点时，他们有效地“删除”了一条可能使某些顶点存活更长时间的边。 核心问题是：可以处理哪些访客，而无需过早立即隔离其两个端点？ 

我们翻转视角。 我们不考虑对来宾进行排序，而是考虑来宾何时成为链接两个仍处于活动状态的组件的第一个连接。 如果我们处理来宾的方式永远不会失去“延迟销毁”组件的能力，直到它不可避免为止，那么我们本质上是在动态维护连接的组件。 

如果我们反向处理客人，这正是不相交集并集 (DSU) 的观点：从存在的所有零食类型开始，逐渐添加客人（边）。 当我们添加一条边时，如果它连接两个已经连接的组件，那么它就形成了一条循环边。 这些边缘对应于不需要维持连接并且可以“最后牺牲”的访客。 这种冗余边的数量正是在最佳排序中可能使客人不满意的数量。 

同样，我们可以模拟处理来宾并计算我们尝试连接 DSU 中已连接的两个顶点的次数。 每个这样的尝试对应于一个循环形成边缘，并且每个循环边缘指示可以将一位客人放置在当他们到达时两种零食实际上已经不可用的位置。 

因此，问题简化为计算在图上构建生成森林时有多少边是多余的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力排列 |$O(k! \cdot (n+k))$|$O(n+k)$| 太慢了 |
 | DSU周期检测|$O((n+k)\alpha(n))$|$O(n)$| 已接受 |

 ## 算法演练

 我们在处理客人时使用不相交集联合结构来保持零食类型之间的连接性。 

1. 初始化 DSU$n$节点，每种零食类型都从其自己的组件开始。 这表示最初没有小吃关系被合并。 
2. 以任意顺序遍历每个来宾。 对于连接的客人$x_i$和$y_i$，尝试将其组件合并到 DSU 中。 
3.如果$x_i$和$y_i$已经在同一个 DSU 组件中，我们不执行联合。 相反，我们增加了“多余客人”的计数器。 这对应于闭合图中的循环而不是扩展连通性的边。 
4. 如果它们位于不同的组件中，我们将它们联合起来，合并组件。 这保留了森林结构。 
5、处理完所有客人后，输出统计的冗余客人数量。 该值是悲伤客人的最小数量。 

这种排序有效的原因是 DSU 正在有效地构建图的生成森林。 任何无法增加连通分量数量的边都不需要维持连通性，并且对应于循环边。 

### 为什么它有效

 在任何时候，DSU 都代表着将零食类型划分为由先前接受的客人形成的连接组件。 当来宾连接同一组件中已有的两个顶点时，该来宾不会有助于扩展可达性； 它仅在已连接的结构内创建替代路线。 这些边正是可以“推迟”的边，直到两个端点都被先前选择的边有效地耗尽为止。 因此，每个形成循环的边缘都对应着一位客人，他们可能会被迫进入他们喜欢的零食都已经消失的位置，这使得他们在任何最佳排序中都感到悲伤。 相反，每个非循环边缘都是连接组件所必需的，并且始终可以以防止悲伤的方式提前安排。 这表明对 DSU 故障进行计数可以得出最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra = self.find(a)
        rb = self.find(b)
        if ra == rb:
            return False
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        return True

def solve():
    n, k = map(int, input().split())
    dsu = DSU(n)
    bad = 0

    for _ in range(k):
        x, y = map(int, input().split())
        if not dsu.union(x, y):
            bad += 1

    print(bad)

if __name__ == "__main__":
    solve()
```DSU 结构维护每种零食类型的代表，并在访客连接两个先前独立的组件时将它们合并。 当边冗余时，即我们增加答案时，union 函数恰好返回 False。 路径压缩可确保每次操作的时间接近恒定，从而保持解决方案的高效。

 ## 边缘情况

 完全无环图，例如简单链$1-2-3-4$，不会产生冗余的 DSU 并集，因此答案为零。 该算法将每条边作为一个成功的并集进行处理，并且不会增加计数器。 

像三角形一样的全循环结构$1-2, 2-3, 1-3$恰好触发一次冗余检测。 前两条边合并组件，而最后一条边找到已连接的两个端点，将答案增加 1。 

断开连接的组件独立运行。 例如，两个单独的链对答案没有任何贡献，因为没有边会关闭每个组件内的循环。
