 ## 解决方案
 ## 问题理解

 战斗队伍包含n个神奇宝贝，每个玩家从两个可能的神奇宝贝中选择一个。 一种选择在任何奖励之前贡献 100 点攻击力，而另一种则贡献 200 点攻击力。 第一个选择很特殊，因为每一个这样的神奇宝贝都会将整个团队的攻击力提高 1.1 倍。 如果有t个特殊神奇宝贝，则全队攻击力乘以1.1的t次方。 

任务是决定n个玩家中有多少人应该选择增强神奇宝贝，以使最终的总攻击力尽可能大。 输入只是玩家数量，输出是最大可能的攻击值。 

约束 n ≤ 50 非常小。 这告诉我们，依赖于尝试所有可能数量的增强 Pokémon 的解决方案已经足够了，因为只有 51 个可能的值需要检查。 更复杂的搜索技术是不必要的，主要挑战是识别数学结构而不是针对大输入大小进行优化。 

一个常见的错误是认为选择攻击力为 200 的更强的神奇宝贝总是最好的。 例如，当 n = 2 时，选择两只攻击力为 200 的神奇宝贝会得到 400，但选择两只增强型神奇宝贝会得到 200 × 1.1² = 242，因此个人攻击力更强的获胜。 然而，对于较大的团队（例如 n = 10），选择所有增强神奇宝贝会得到 100 × 10 × 1.11⁰，这比仅选择 200 攻击神奇宝贝要大。 乘法会影响每个神奇宝贝，因此忽略全局奖励会给出错误的答案。 

另一个边缘情况是 n = 1。仅检查所有 Pokémon 是否应接收乘数的粗心实现可能会输出 110，但正确的选择是 100 或 200，因此答案是 200。仅当 Pokémon 数量的增加补偿了较低的基本攻击力时，奖励才有用。 

## 方法

 直接的方法是尝试所有可能数量t的增强神奇宝贝。 对于固定的 t，队伍有 t 只基本攻击力为 100 的神奇宝贝和 n - t 只基本攻击力为 200 的神奇宝贝，因此未经修改的攻击力为 100t + 200(n - t)，简化为 200n - 100t。 应用团队范围的乘数后，最终值为：

 100t + 200(n - t) 乘以 1.1^t。 

由于 t 只能是 0 到 n 之间的整数，因此检查所有可能性足以找到最佳值。 这种暴力法实际上是最终的解决方案，因为 n 很小。 在最坏的情况下，它执行 51 次评估，这是微不足道的。 

如果 n 大得多，我们将需要利用更多的数学特性。 蛮力之所以有效，是因为候选者的数量有限，但如果玩家数量增加到数百万，它的吸引力就会降低。 在这里，观察到唯一的决策变量是增强 Pokémon 的数量，从而将问题从在 2^n 个团队组成中进行选择减少到检查 n + 1 个可能的数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 已接受 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将最佳答案初始化为零。 我们将把 t 的每个可能值与该变量进行比较。 
2. 考虑从 0 到 n 的每个 t，其中 t 代表增强神奇宝贝的数量。 无需知道哪些玩家选择了他们，因为所有具有相同选择的玩家都是相同的。 
3. 计算当恰好选择t个增强神奇宝贝时团队的基本攻击力。 该值为 100t + 200(n - t)。 
4. 将基础攻击力乘以 1.1^t，以应用所有增强神奇宝贝的效果。 每个增强神奇宝贝都会影响整个团队，因此在添加所有基本攻击后应用乘数。 
5. 用迄今为止看到的最大值更新最佳答案，并在检查完所有选项后打印结果。

为什么有效：每种可能的团队组成都由一个 t 值（增强神奇宝贝的数量）来表示。 对于固定的 t，具有相同计数的所有选择都会产生相同的攻击值，因为各个玩家的身份并不重要。 由于该算法会评估每个可能的 t，因此它找到的最大值必定是最佳可能的团队攻击。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    ans = 0.0

    for t in range(n + 1):
        base = 100 * t + 200 * (n - t)
        attack = base * (1.1 ** t)
        if attack > ans:
            ans = attack

    print("{:.15f}".format(ans))

if __name__ == "__main__":
    solve()
```该程序读取玩家数量并测试 t 的每个可能值。 循环使用`range(n + 1)`因为两个极端都很重要：t = 0 意味着每个玩家都选择 200 攻击的神奇宝贝，而 t = n 意味着每个玩家都选择增强的神奇宝贝。 

变量`base`在乘数之前存储攻击。 乘数是通过浮点求幂计算的，因为答案不一定是整数。 Python 的浮点精度足以满足所需的容错能力。 

输出使用小数点后十五位数字。 这不是问题所必需的，但它提供了足够的精度以避免格式问题。

 ## 边缘情况

 对于 n = 1，算法检查 t = 0 和 t = 1。当 t = 0 时，攻击为 200 × 1 = 200。当 t = 1 时，攻击为 100 × 1.1 = 110。算法保留 200，这与正确选择匹配。 

对于 n = 2，输入为：```
2
```该算法计算 t = 0、1 和 2。值分别为 400、330 和 242，因此最终答案为 400。这可以处理单个 200 次攻击的神奇宝贝比接收额外乘数更好的情况。 

对于 n = 10，输入为：```
10
```该算法检查从 0 到 10 的所有值。最佳值出现在 t = 10 时，此时攻击变为 1000 × 1.11⁰ = 2593.742460100002063。 这证实了当有足够多的神奇宝贝参与时，全局乘数可以占据主导地位。 

对于 n = 50，循环仍仅执行 51 次迭代。 该实现通过使用浮点值进行最终计算来避免整数溢出，因此可以安全地处理最大约束。
