 ## 解决方案
 ## 问题理解

 我们得到了系统中已经存在的测试索引。 每个索引都是正整数，并且所有索引都是不同的。 任务是找到没有出现在列表中的最小正整数。 

这是经典的“最小缺失正值”想法，但约束足够小，我们不需要任何高级数据结构。 现有测试数量最多为3000个，每个指标也最多为3000个。$O(n^2)$在最坏的情况下，解决方案执行大约 900 万次操作，这很容易满足 Python 中 2 秒的限制。 

主要困难不是性能，而是正确处理搜索。 答案不是最大值加一，除非每个较小的正整数都已经存在。 

考虑这个输入：```
3
1 7 2
```正确答案是`3`， 不是`8`。 下一个索引必须是最小的未使用正数。 

另一个容易犯的错误是从以下位置开始搜索`0`。 测试指数仅为正整数。 

例子：```
4
2 3 4 5
```正确答案是`1`因为最小的正整数立即丢失。 

当所有值来自`1`到`n`存在。 

例子：```
5
1 2 3 4 5
```答案就变成了`6`。 仅检查数组中已存在的数字的粗心实现可能永远不会打印任何内容。 

## 方法

 蛮力方法很简单。 开始于`1`并反复检查数组中是否存在当前数字。 第一个未找到的数字就是答案。 

为了测试某个值是否存在，我们可以线性扫描整个数组。 由于最多可以有 3000 个候选值，并且每次搜索可能检查所有 3000 个元素，因此最坏情况的复杂度变为$O(n^2)$。 

对于这个问题，即使这样也足够快了。 Python 中可以接受大约 900 万次比较。 

尽管如此，问题结构为我们提供了一个更清晰的解决方案。 我们只关心一个数字是否存在，而不关心它出现在哪里。 这意味着成员资格查询是核心操作。 集合平均支持成员资格检查$O(1)$时间。 

观察很简单：一旦将值存储在集合中，我们就可以测试数字`1, 2, 3, ...`一个接着一个，直到找到第一个缺失值。 

答案最多保证是`n + 1`。 如果有`n`不同的正整数和所有数字`1`通过`n`存在，那么`n + 1`失踪了。 这最多让我们在检查后停止`n + 1`候选人。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(1)$| 已接受 |
 | 最佳 |$O(n)$平均 |$O(n)$| 已接受 |

 ## 算法演练

 1.读取整数`n`以及现有测试索引的列表。 
2. 将所有索引存储在一个集合内。 

集合允许快速的成员资格检查，这正是我们在询问“这个号码是否已经存在？”时所需要的。 
3. 迭代以下整数`1`到`n + 1`。 

答案不能超过`n + 1`。 如果每个值来自`1`通过`n`存在，那么最小的缺失正数一定是`n + 1`。 
4. 对于每个整数`x`，检查集合中是否存在。 

如果`x`不存在，打印`x`立即停止。 
5. 扫描过程中遇到的第一个缺失的数字是所需的下一个测试索引。 

### 为什么它有效

 该算法按升序检查正整数。 在达到某个值之前`x`，每个较小的正整数都已被验证存在于集合中。 什么时候`x`是第一个未找到的值，它恰好是数组中缺少的最小正整数。 

由于扫描按顺序进行并在第一个间隙处停止，因此算法无法跳过较小的有效答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# solution

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    used = set(arr)

    for x in range(1, n + 2):
        if x not in used:
            print(x)
            return

solve()
```第一步读取输入数组并将其转换为名为的集合`used`。 此转换是关键的优化，因为成员资格检查平均时间变为恒定时间。 

循环运行自`1`通过`n + 1`包容性。 上限很重要。 如果所有数字都来自`1`到`n`存在，则答案必须是`n + 1`。 使用`range(1, n + 1)`会错过那个案例。 

一旦发现缺失值，该函数就会打印它并立即返回。 无需继续扫描，因为我们按升序处理数字。 

这里不存在整数溢出问题，因为所有值都非常小。 实现主要是关于仔细的边界和正确的停止条件。

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    arr = list(map(int, input().split()))

    used = set(arr)

    for x in range(1, n + 2):
        if x not in used:
            print(x)
            return

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    backup_stdout = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup_stdout
    return out.getvalue().strip()

# provided sample
assert run("3\n1 7 2\n") == "3", "sample 1"

# minimum size input
assert run("1\n1\n") == "2", "single existing value"

# missing 1

# consecutive sequence
assert run("5\n1 2 3 4 5\n") == "6", "answer is n + 1"

# unordered values
assert run("6\n4 2 1 6 3 7\n") == "5", "handles unsorted input"

# maximum-style boundary pattern
assert run("3\n3000 2999 1\n") == "2", "large values do not matter"

 ## 边缘情况

 考虑以下情况`1`立即失踪。 

输入：```
4
2 3 4 5
```该集合变为`{2, 3, 4, 5}`。 该算法从开始检查`1`。 自从`1`不存在，它打印`1`立即地。 这可以正确处理最小的可能答案。 

现在考虑以下情况：所有值都来自`1`通过`n`存在。 

输入：```
5
1 2 3 4 5
```算法检查`1`,`2`,`3`,`4`， 和`5`，所有这些都存在于集合中。 然后它检查`6`，缺少它，所以它打印`6`。 这就是为什么循环必须运行直到`n + 1`。 

最后，考虑有间隙的无序输入。 

输入：```
6
7 3 1 2 6 4
```该集合变为`{1, 2, 3, 4, 6, 7}`。 检查过程如下：

 -`1`存在
 -`2`存在
 -`3`存在
 -`4`存在
 -`5`不存在

 算法打印`5`。 原始顺序并不重要，因为集合只存储成员信息。
