 ## 解决方案
 ## 问题理解

 我们得到一个由字符组成的字符串`0`,`1`， 和`?`。 该字符串的每个完整版本都定义了一个生成值序列的数字过程。 

我们从`c0 = 0`。 然后我们从左到右扫描字符串。 每个字符都会将当前值转换为下一个值。 一个`0`增加值`x`，同时一个`1`翻转标志`y`，生产`y - current value`。 处理整个字符串后，我们将所有中间值相加`c1 + c2 + ... + cn`，它给出与该完整字符串关联的单个数字。 

任务不是评估一项完成情况。 相反，每个`?`可以替换为`0`或者`1`，产生许多可能的最终总和。 每个这样的总和称为“酷”，我们必须计算所有不同酷值的总和。 

关键的困难在于不同的任务`?`可以导致相同的最终总和，因此我们不计算配置，而是聚合它们的结果值。 

这些约束立即排除了对所有完成情况的强力枚举。 总共有多达 100,000 个职位，每个职位都有指数级的选择`?`，尝试所有字符串是不可能的。 即使子集上的每次测试指数 DP 也会爆炸。 

一个更微妙的问题是循环交替行为：`0`保持线性增长，同时`1`引入反射`y - c_{i-1}`，这使得值取决于先前操作的奇偶性。 忽略这种交替结构的朴素前缀模拟将错误计算贡献，因为`1`不是加法而是状态翻转。 

当多个`?`以长交替模式存在。 贪婪替换或局部推理失败，因为早期选择通过符号反转影响所有未来值。 

## 方法

 蛮力方法会尝试所有方法来替换每一个`?`和`0`或者`1`。 对于每个完整的字符串，我们模拟递归并计算`f(s)`。 这是正确的，因为它直接遵循定义。 然而，如果有`m`问号，这导致`2^m`配置以及每次评估成本`O(n)`。 即使对于中等`m`，这变得不可行。 

递归的结构提出了不同的观点。 每一步都与前一个值呈线性关系：`0`适用`c -> c + x`，同时一个`1`适用`c -> -c + y`。 这是仿射变换。 因此，整个过程是仿射函数的组合，这意味着每个前缀状态都可以写为：```
c_i = a_i * c_0 + b_i
```自从`c0 = 0`，我们只跟踪`b_i`，但关键的见解是每一步都会切换未来贡献的标志。 因此，每个前缀状态取决于有多少个的奇偶校验`1`到目前为止已应用。 

我们没有跟踪所有分配的精确值，而是将贡献分为两部分：假设所有选择都是固定的基本贡献，以及每个选择引起的附加效果`?`在两个线性行为之间切换。 这将问题转化为一个小状态空间上的动态规划，描述当前前缀是处于“正常”还是“翻转”奇偶校验，并结合计算有多少分配导致每个状态。 

本质上的减少是每个位置贡献一个固定的增量（`0`）或翻转未来积累的转换（`1`）。 这使我们能够为每个前缀维护值的总和以及在每个奇偶校验状态下到达该前缀的方式数量，并以每个字符的 O(1) 更新它们。 

最终答案是通过汇总这些 DP 状态的所有有效完成的贡献来获得的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^k·n) | O(2^k·n) | O(n) | 太慢了 |
 | DP 超过奇偶校验状态 | O(n) | O(1) 或 O(n) | 已接受 |

 ## 算法演练

 我们将这个过程重新解释为在扫描字符串时维护两种类型的信息：有多少种方式导致给定的符号状态，以及该状态下所有前缀的累积贡献。 

在每个位置，转换仅取决于我们是否选择`0`,`1`，或者有一个强制值。 

我们维护四个聚合：

 1. 以正向到达当前位置的方式数量。 
2. 负方向到达当前位置的方式数量。 
3.正向定向前缀贡献的总和。 
4.负向前缀贡献的总和。 

方向跟踪当前值是否表现正常或由于奇数个而被否定`1`-类型转换。 

我们从左到右处理字符。 

1.初始化：在读取字符串之前，有一种方法是用sum正向定向`0`。 
2. 对于每个字符，计算转换：

 - 如果角色是`0`，变换添加`x`到当前值而不翻转方向。 
- 如果角色是`1`，它应用翻转：下一个值变为`y - c`，它会改变方向并添加固定偏移。 
- 如果角色是`?`，我们分为两个转变并结合它们的贡献。 
3. 首先更新计数，然后更新贡献总额。 这种排序至关重要，因为方式的数量会影响固定增量对总和的贡献程度。 
4. 最后，将两个方向的贡献合并起来，得出所有完成情况的总和。 

关键的不变量是处理后的位置`i`，DP正确表示前缀的所有部分分配`s[1..i]`，按当前循环状态是否翻转进行分组。 每个 DP 条目准确地存储所有此类分配的聚合贡献，因此以后不会发生重组或重复计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, x, y = map(int, input().split())
    s = input().strip()

    # dp0, dp1: number of ways in state 0/1
    # sum0, sum1: sum of c_i contributions aggregated over all ways
    dp0 = 1
    dp1 = 0
    sum0 = 0
    sum1 = 0

    for ch in s:
        n0 = n1 = 0
        ns0 = ns1 = 0

        if ch == '0' or ch == '?':
            # 0: c -> c + x, no flip
            n0 += dp0
            ns0 += sum0 + dp0 * x

            n1 += dp1
            ns1 += sum1 + dp1 * x

        if ch == '1' or ch == '?':
            # 1: c -> y - c (flip orientation)
            n1 += dp0
            ns1 += dp0 * y - sum0

            n0 += dp1
            ns0 += dp1 * y - sum1

        dp0, dp1 = n0 % MOD, n1 % MOD
        sum0, sum1 = ns0 % MOD, ns1 % MOD

    ans = (sum0 + sum1) % MOD
    print(ans % MOD)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```DP 同时维护计数和累加总和。 过渡为`0`将每个活动配置的当前值增加`x`，因此总和增加`dp * x`除了结转以前的款项外。 

为了`1`，我们应用变换`y - c`。 这反转了贡献方向，因此在固定的情况下减去先前的总和`y`为每个活动配置添加术语。 

在取模之前必须注意始终更新状态计数和总贡献。 在减法中早期混合模可能会导致负值破坏以后的转换，因此首先以全精度进行减法，并仅在赋值时进行减法。

 ## 边缘情况

 当字符串在之间频繁交替时，会出现微妙的边缘情况`1`和`?`。 在这种情况下，方向会反复翻转，假设单调累积的简单实现会失败。 

例如，考虑`s = "?1"`。 第一个角色创建两个方向，第二个角色将它们翻转回来。 正确的DP必须分别保留两个分支； 过早合并它们会导致取消本应保持明确的术语。 

Tracing`?1`:

 开始于`(dp0, dp1) = (1, 0)`。 

后`?`， 两个都`0`和`1`各州均处于活跃状态。 加工后`1`，转换交换状态并减去之前的总和，但 DP 结构将两个贡献分开。 最终的聚合与显式枚举两个完成保持一致。 

这证实了方向状态不变足以防止重复翻转过程中的信息丢失。
