 ## 解决方案
 ## 问题理解

 杰克从位置开始`0`在数轴上。 他的跳跃有固定的长度：第一次跳跃必须有长度`1`，第二次跳跃长度`2`，第三次跳跃长度`3`， 等等。 每次跳跃他都可以选择任一方向。 任务是找到精确着陆位置所需的最少跳跃次数`x`。 

方向的选择是有趣的部分。 后`k`跳跃时，移动的总距离始终为：$1+2+3+\dots+k=\frac{k(k+1)}{2}$我们唯一控制的是哪些跳跃是正的，哪些是负的。 

输入大小可达`10^9`，这立即排除了对位置的任何状态空间搜索。 对可达坐标的广度优先搜索将会爆炸，因为之后`k`跳跃有`2^k`方向选择。 甚至`k = 40`已经产生了超过一万亿种可能性。 

答案本身仍然很小，因为三角数呈二次方增长。 达到周围距离`10^9`，我们只需要粗略地：$\frac{k(k+1)}{2}\approx 10^9$这给出了`k ≈ 44721`。 这意味着`O(sqrt(x))`解决方案是完全安全的。 

负面目标很容易犯错误。 该问题是关于零对称的，因为左右跳跃的每个序列都可以镜像。 达到`-5`需要跳跃的次数与到达的次数相同`5`。 单独处理负值的粗心实现可能会带来不必要的复杂性。 

当累计总和首次超过目标但奇偶校验错误时，会出现另一种微妙的情况。 例如：

 输入：```
2
```两次跳跃后，总距离为`1 + 2 = 3`。 我们无法使`2`因为改变跳跃方向会使最终位置改变两倍于跳跃长度。 区别`3 - 2 = 1`是奇数，所以没有任何跳跃子集可以修复它。 我们还需要再跳一次，总计`6`，现在`6 - 2 = 4`是偶数，所以答案变成`3`。 

第二个奇偶校验陷阱是：

 输入：```
5
```三跳后的总和是`6`，已经超过了`5`， 但`6 - 5 = 1`很奇怪。 四次跳跃后，总和变为`10`， 和`10 - 5 = 5`仍然很奇怪。 只有五次跳跃后我们才能得到`15 - 5 = 10`，这是偶数。 正确答案是`5`， 不是`3`或者`4`。 

## 方法

 蛮力的想法很简单。 跳跃时`i`，选择向左或向右并递归继续。 后`k`跳跃有`2^k`可能的路径。 该方法是正确的，因为它探索了每一个合法的方向序列，但它几乎立即变得无用。 即使只有`40`跳跃，搜索空间超过一万亿个状态。 

关键的观察是只有签名总和才重要。 假设之后`k`跳跃总距离为：$S=1+2+\dots+k$如果我们最初想象所有的跳跃都是向右的，那么我们的着陆点是`S`。 翻转跳跃长度`d`向相反方向改变最终位置`2d`，因为跳跃有助于`+d`而不是`-d`。 

所以之后的每个可到达的位置`k`跳跃的形式为：$S-2t$在哪里`t`是跳跃长度的某个子集的总和。 

这立即给出了达到的两个必要条件`x`。 

第一的，`S`必须至少是`|x|`，否则我们根本就没有足够的总运动量。 

第二，`S - |x|`必须是偶数，因为它等于`2t`。 

美妙的是，这些条件也足够了。 既然数字`1,2,3,...,k`可以形成每个值`0`到`S`，任何偶数差异都可以通过翻转适当的跳跃子集来纠正。 

这将问题简化为寻找最小的`k`这样：$\frac{k(k+1)}{2}\ge |x|$和$\left(\frac{k(k+1)}{2}-|x|\right)\bmod 2=0$我们可以简单地继续增加`k`直到两个条件都成立。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^k) | O(2^k) | O(k) | 太慢了|
 | 最佳| O(sqrt(x)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取目标位置`x`。 
2. 更换`x`和`abs(x)`。 达到`-x`需要与到达相同的跳跃次数`x`因为每个方向都可以镜像。 
3. 初始化`k = 0`和`total = 0`。 这里`k`是迄今为止使用的跳跃次数，并且`total`是总和`1 + 2 + ... + k`。 
4、反复增加`k`加一并添加到`total`。 
5. 每次更新后，检查两个条件：

 1.`total >= x`2.`(total - x) % 2 == 0`6. 当两个条件都满足时立即停止。 此时我们知道可以翻转跳转的某些子集以准确地产生`x`。 
7. 输出`k`。 

奇偶校验是核心见解。 翻转跳跃将最终坐标更改为偶数，因此两者之间的差异`total`和`x`必须是均匀的。 

### 为什么它有效

 之后`k`跳跃时，最大可达坐标为`total = 1 + 2 + ... + k`。 任何其他可到达的坐标都是通过翻转一些跳跃来获得的，并且每次翻转的跳跃都会改变最终值`2d`。 这意味着每个可到达的坐标都不同于`total`偶数。 

因此，可达位置恰好是具有相同奇偶校验的所有整数`total`区间内`[-total, total]`。 

该算法搜索第一个`k`在哪里`x`位于这个可达集合内。 自从我们测试`k`按升序排列，第一个有效的答案是最小答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

x = abs(int(input()))

k = 0
total = 0

while total < x or (total - x) % 2 != 0:
    k += 1
    total += k

print(k)
```该实现直接反映了数学推理。 

第一行将目标转换为其绝对值。 这消除了分别考虑左和右的需要。 答案为`-17`与答案相同`17`。 

变量`k`和`total`跟踪当前的跳跃次数以及这些跳跃后的三角和。 每次迭代都会模拟添加下一个强制跳跃长度。 

循环条件包含两个必需的属性。 第一部分检查我们是否已经积累了足够的距离来达到目标​​。 第二部分检查奇偶校验兼容性。 

一个常见的错误是一旦停止就立即停止`total >= x`。 这在类似的情况下失败了`x = 2`， 因为`3`和`2`有不同的奇偶性。 另一个错误是在验证之前检查奇偶校验`total >= x`，它可能会意外地接受不可能的状态。 

Python 整数自动处理大值，因此不存在溢出风险。 在具有固定宽度整数的语言中，32 位有符号整数在这里仍然足够，因为最大的三角和保持在附近`10^9`。

import sys
import io

def solve():
    import sys
    input = sys.stdin.readline

    x = abs(int(input()))

    k = 0
    total = 0

    while total < x or (total - x) % 2 != 0:
        k += 1
        total += k

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

 ## 边缘情况

 考虑输入：```
0
```该算法立即成功，因为`total = 0`已经满足这两个条件了。 循环永远不会运行，答案是正确的`0`。 

现在考虑：```
-2
```该算法将其转换为`2`。 迭代变得与之前的示例相同。 三跳后我们有`total = 6`， 和`6 - 2 = 4`是偶数，所以答案是`3`。 镜像方向改变了任何解决方案`2`成解决方案`-2`。 

奇偶校验陷阱清楚地出现在：```
2
```两次跳跃后总数为`3`。 自从`3 - 2 = 1`是奇数，没有任何跳跃子集可以精确调整位置`2`。 该算法正确地继续了一步。 

一个更微妙的奇偶校验情况是：```
5
```总数演变为`1, 3, 6, 10, 15`。 前两个总数太小。 接下来的两个有奇怪的区别`5`。 仅有的`15`产生均匀的差异。 算法正确输出`5`。
