 ## 解决方案
 ## 问题理解

 我们有一个整数数组，我们希望每个元素都严格大于它前面的元素。 唯一允许的操作是选择单个元素并将其精确增加`d`。 每次使用此操作都算作一次移动。 

任务是找到将数组转换为严格递增序列所需的最少移动次数。 

约束足够小，即使是二次解也能轻松通过。 和`n ≤ 2000`， 一个`O(n²)`在最坏的情况下，算法会执行大约 400 万次操作，这对于 Python 中的 1 秒限制来说已经足够了。 同时，问题的结构表明我们应该能够在一次传递中贪婪地处理数组。 

关键的观察是每个位置仅取决于前一个位置。 一旦我们决定了最终的价值`a[i-1]`，最小有效值`a[i]`是固定的：它必须至少成为`a[i-1] + 1`。 

一些边缘情况很容易破坏粗心的实现。 

考虑一个已经在增加的数组：```
3 5
1 7 20
```答案是`0`。 错误的实现可能仍然会应用操作，因为它会检查`<=`错误地或不必要地更新值。 

相邻值相等是另一个常见的陷阱：```
3 2
1 1 1
```正确答案是`3`。 

序列的演变如下：```
1 1 1
1 3 1
1 3 5
```第二个元素需要一次操作，但第三个元素现在必须超过`3`，不是原来的`1`。 修改后忘记更新数组会产生错误的计数。 

当间隙不能被整除时，会出现更微妙的情况`d`:```
2 3
5 6
```数组已经在增加，所以答案是`0`。 

但对于：```
2 3
5 5
```第二个值必须至少变为`6`。 一项操作将其更改为`5`到`8`，所以答案是`1`。 

使用普通整数除法，例如：```
needed = (target - current) // d
```在这里失败是因为`1 // 3 = 0`。 我们需要天花板划分。 

另一个棘手的例子是：```
2 4
10 1
```第二个值必须超过`10`，所以它必须至少达到`11`。 

可达值的序列是：```
1 -> 5 -> 9 -> 13
```需要三个动作，而不是两个。 

## 方法

 蛮力方法很简单。 我们从左到右扫描数组。 每当`a[i]`并不严格大于`a[i-1]`，我们反复添加`d`直到条件成立。 每次添加都算作一次移动。 

这种方法是正确的，因为每次操作都只会增加当前元素，提前增大它永远不会损害未来的位置。 问题是效率。 如果`d = 1`而且差距很大，我们可能会进行很多单独的补充。 在最坏的情况下，值可能会增长到数百万，从而导致循环迭代次数不必要地增加。 

例如：```
2 1
1000000 1
```第二个元素需要 1,000,000 次循环迭代。 

关键的见解是我们永远不需要一一模拟添加。 对于当前值`x`以及所需的最低限度`need`，我们可以直接计算需要添加多少个。 

我们想要：```
x + k*d > previous
```等效地：```
x + k*d >= previous + 1
```所以：```
k >= (previous + 1 - x) / d
```最小有效整数`k`是该分数的上限。 

这将重复更新的蛮力转化为直接的数学计算。 我们仍然从左到右处理数组，但每个位置都是在恒定时间内处理的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(总操作) | O(1) | O(1) | 可能太慢 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取数组并将答案计数器初始化为`0`。 
2.从index开始从左到右处理数组`1`。 
3. 对于每个位置，检查是否`a[i] > a[i-1]`。 
4. 如果条件已成立，则移至下一个元素，因为该位置不需要更改。 
5. 否则，计算当前元素必须达到的最小值：```
target = a[i-1] + 1
```6. 计算添加了多少个`d`需要至少达到`target`。 

所需增加量为：```
target - a[i]
```由于每个操作都精确地相加`d`，操作次数为：```
ceil((target - a[i]) / d)
```在整数运算中：```
ops = (target - a[i] + d - 1) // d
```7. 添加`ops`到答案。 
8. 更新当前数组值：```
a[i] += ops * d
```这个更新后的值成为下一个元素的参考。 

### 为什么它有效

 该算法在处理索引后保持了不变式`i`, 前缀`a[0...i]`严格以尽可能少的操作次数递增。 

加工时`a[i]`，先前的值已经最佳固定。 任何有效的最终值`a[i]`必须大于`a[i-1]`。 选择最小的可达到值始终是最佳的，因为`a[i]`不必要的大只会使未来的元素更难以满足。 由于每个操作都会精确地改变值`d`，上限除法计算所需的确切最小操作数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, d = map(int, input().split())
a = list(map(int, input().split()))

answer = 0

for i in range(1, n):
    if a[i] <= a[i - 1]:
        target = a[i - 1] + 1
        ops = (target - a[i] + d - 1) // d

        answer += ops
        a[i] += ops * d

print(answer)
```解决方案直接遵循贪婪的从左到右策略。 

循环从索引开始`1`因为第一个元素永远不需要修改。 对于每个位置，我们只关心前一个值。 较早的元素已经形成了最佳的递增前缀。 

上限划分公式是最重要的实现细节：```
(target - a[i] + d - 1) // d
```当所需的增量不是 的倍数时，使用普通除法就会失败`d`。 

数组更新：```
a[i] += ops * d
```也是必不可少的。 未来的元素必须与修改后的值进行比较，而不是与原始值进行比较。 

Python 整数自动处理大值，因此不必担心溢出。

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n, d = map(int, input().split())
    a = list(map(int, input().split()))

    answer = 0

    for i in range(1, n):
        if a[i] <= a[i - 1]:
            target = a[i - 1] + 1
            ops = (target - a[i] + d - 1) // d

            answer += ops
            a[i] += ops * d

    print(answer)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample

# minimum size, already increasing

 ## 边缘情况

 考虑相等的相邻值：```
3 2
1 1 1
```在索引处`1`，之前的值是`1`，因此目标变为`2`。 一项操作将值更改为`1`到`3`。 

现在数组是：```
1 3 1
```在索引处`2`，之前的值现在是`3`，因此目标变为`4`。 两个操作发生变化`1`进入`5`。 

总业务：```
1 + 2 = 3
```该算法之所以成功，是因为它始终与更新后的先前值进行比较。 

现在考虑一种情况，其中所需的增加不能被整除`d`:```
2 4
7 4
```第二个值必须至少变为`8`。 

所需增加量为：```
8 - 4 = 4
```一次操作就足够了：```
4 + 4 = 8
```公式计算：```
(4 + 4 - 1) // 4 = 1
```这是正确的。 

最后，考虑一个已经有效的序列：```
4 10
1 20 30 40
```每个元素都已经满足严格的不等式。 条件：```
if a[i] <= a[i - 1]:
```永远不会触发，所以答案仍然存在`0`。 

这证实了该算法不会执行不必​​要的操作。
