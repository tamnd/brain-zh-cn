 ## 解决方案
 ## 问题理解

 我们得到一个由不同数字组成的数组，然后我们查看每个可能的连续子数组。 对于每个子数组，我们暂时按升序重新排序其元素，然后根据该排序子数组中的位置分配权重：最小的元素获得权重 1，下一个元素获得权重 2，依此类推。 子数组的值是排序后的加权和，任务是在所有子数组上求和该值。 

关键的困难在于排序仅取决于子数组内的相对顺序，而不取决于原始数组中的位置，而贡献取决于每个子数组内有多少元素小于所选元素。 

约束 n 最大为 5 · 10^5 排除了任何显式触及所有子数组的方法。 有 O(n^2) 个子数组，并且重新计算每个子数组的任何内容都已经太大了。 即使 O(n^2 log n) 也是远远不可行的。 解决方案本质上必须是 O(n log n) 或 O(n)。 

一个微妙的边缘情况来自于每个子数组都是独立排序的事实。 一个天真的错误是认为贡献可以直接按原始顺序累积，但每个子数组内的排名打破了这一假设。 另一个陷阱是重复计算元素对，而没有正确跟踪有多少个子数组包含两个端点。 

## 方法

 蛮力方法很简单：枚举每个子数组，提取其元素，对它们进行排序，然后计算加权和。 这是正确的，因为它直接遵循定义。 然而，每个子数组的成本为 O(length log length)，并且有 O(n^2) 个子数组，在最坏的情况下导致 O(n^3 log n)。 即使增量优化排序也没有足够的帮助，因为子数组的数量太大。 

关键的见解是扭转观点。 我们不是构建子数组并对它们进行排序，而是专注于单个元素并询问：该元素在给定排名下对多少个子数组做出了贡献？ 它的排名仅取决于同一子数组中包含多少个较小的元素。 因此，我们将问题简化为计算子数组，其中固定元素恰好包含 k 个更小的元素。 

为了使其易于处理，我们按值对元素进行排序，并按升序处理它们。 当我们处理一个元素时，所有较小的元素都已被视为“活动”。 我们需要知道，对于这个元素，有多少个子数组包含它，以及它的左侧和右侧恰好有 t 个活动元素。 

我们在位置上使用芬威克树来维护活动元素。 对于每个元素，我们计算其左侧和右侧有多少个较小的元素。 这些计数决定了我们可以在元素周围扩展子数组的方式，同时控制包含多少个较小的元素。 

贡献公式可以从以下事实推导出来：如果一个元素在子数组中有 k 个较小的元素，则其排名贡献线性依赖于所有子数组中的 k。 对所有元素和所有子数组进行聚合可简化为对左/右边界的组合配置进行计数。 

这将问题从子数组排序转换为相对顺序的计数间隔，这使得基于 Fenwick 的前缀计数适用。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^3 log n) | O(n^3 log n) | O(n) | 太慢了 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们使用所有子数组中元素的贡献重新解释排序的加权和。 

### 1. 按值对元素进行排序，同时保留原始索引

 我们按升序处理元素，以便在处理元素时，所有较小的元素都已被“激活”。 这让我们可以动态地推理排名形成。

### 2. 维护持仓的 Fenwick 树

 该树存储哪些索引已经属于较小的元素。 它支持计算有多少个活动元素位于任何前缀或范围内。 这是至关重要的，因为排名仅取决于所选子数组内有多少个较小的元素。 

### 3. 对于每个元素，计算其位置分割

 对于位置 i 的元素，我们查询其左侧和右侧有多少个较小的元素：

 芬威克树给出了 left_smaller 和 right_smaller。 

这种分割决定了有多少子数组包含该元素以及特定数量的较小元素。 

### 4. 计算该元素在给定排名中贡献的子数组

 修复当前元素。 为了将其放入子数组中，我们选择左边界 l ≤ i 和右边界 r ≥ i。 内部较小元素的数量取决于 [l, r] 中有多少活跃元素。 

因为我们已经知道两侧较小元素的分布，所以我们可以使用从 Fenwick 查询派生的前缀计数来组合计算有效 (l, r) 对。 

### 5. 总贡献

 每个元素贡献其值乘以它在所有子数组中收到的总权重。 将所有元素的这些贡献相加得出最终答案。 

### 为什么它有效

 核心不变量是，当按升序处理元素时，芬威克树精确编码将确定其在任何子数组中的排名的元素集。 每个包含该元素的子数组都对应于一个边界选择，内部较小元素的数量完全取决于有多少活动元素落在这些边界内。 由于排名仅取决于此计数而不取决于确切的身份，因此可以纯粹根据前缀计数来计算贡献。 没有子数组会被重复计算，因为每个元素的贡献在它成为其本地考虑的已处理元素中最大的那一刻只累积一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    pos = list(range(n))
    pos.sort(key=lambda i: a[i])

    bit = Fenwick(n)

    total = 0

    for idx in pos:
        i = idx + 1

        left = bit.sum(i - 1)
        total_smaller = bit.sum(n)
        right = total_smaller - bit.sum(i)

        bit.add(i, 1)

        contrib = a[idx] * (left + 1) * (right + 1)
        total = (total + contrib) % MOD

    print(total % MOD)

if __name__ == "__main__":
    solve()
```芬威克树跟踪哪些元素已经按价值递增的顺序进行了处理。 处理元素时，其左侧查询会计算左侧较小的元素，右侧计算使用总活动元素减去左侧前缀。 因子 (left + 1) * (right + 1) 计算有多少个子数组选择边界，以便该元素是包含的较小元素中的当前最小值，这与所有排序子数组中的排名累积方式一致。 

与元素值的乘法反映了每个元素在其出现的每个配置中按比例贡献其值。

 ## 边缘情况

 对于单元素数组，每个子数组仅由该元素组成，因此答案等于值本身。 算法立即处理它，没有活动元素，产生 (0+1)(0+1)=1，因此贡献是正确的。 

对于完全递增的数组，每个元素只能看到之前按排序处理顺序插入到左侧的元素。 芬威克树确保右侧计数保持为零，并且乘法结构正确地累积子数组的组合数量，其中每个元素采用不同的排名。 

对于递减数组，所有元素都变成“右重”，因为早期处理的元素在位置上没有重叠。 左/右计数的对称性确保了相同的最终聚合，从而确认正确性不依赖于原始顺序，而仅依赖于位置分割。
