 ## 解决方案
 ## 问题理解

 我们得到了一个有效的括号字符串。 将其视为从高度 0 开始的步行，其中每个左括号将高度增加 1，每个右括号将高度减少 1，并且步行永远不会变为负数并以 0 结束。 

任务是将这个单一平衡结构拆分为两个子序列，一个用 0 标记，另一个用 1 标记，而不改变顺序。 每个子序列本身必须保持有效的平衡括号序列。 因此，在仅过滤标签 0 的字符后，我们仍然必须具有正确的括号结构，对于标签 1 也必须如此。 

在所有有效的分割中，我们希望最小化两个结果序列的较大嵌套深度。 嵌套深度对应于该子序列自己的前缀和视图中达到的最大高度。 

最大 2×10^5 的约束 n 立即排除了尝试所有分区或对每个分割执行嵌套验证的任何方法。 任何解决方案都必须是线性或接近线性的，因为 O(n log n) 是可以接受的，但 O(n^2) 则不行。 

当人们试图仅根据“替代颜色”或“按位置奇偶性分割”等局部决策贪婪地分配括号时，就会出现一种微妙的失败模式。 例如，在字符串“((()))”中，交替颜色给出红色“(()”和蓝色“(()”，两者都无效，因为两者都不能保持平衡。另一个天真的想法是始终按当前深度奇偶校验分配，但如果不控制push/pop结构的一致性，即使总序列很好，一种颜色也可能变得不平衡。

 关键的困难在于有效性取决于每种颜色内一致的打开和关闭匹配，而不仅仅是全局结构。 

## 方法

 一个蛮力的想法是以所有可能的方式为每个括号分配两种颜色之一，并检查两个诱导序列的有效性。 有 2^n 次分配，对于每个分配，我们都需要对两个括号序列进行线性验证，从而导致 O(n·2^n)，这远远超出了限制。 

我们需要利用常规括号序列的结构。 关键的观察结果是，在规范匹配中，每个左括号都可以恰好与一个右括号配对，并且这些对形成树状嵌套结构。 

关键的见解是将序列解释为深度行走。 在每个位置，我们都知道当前的深度。 该问题简化为将所有括号分成两个堆栈，以便每个堆栈独立地形成有效的深度行走。 确保有效性的简洁方法是保证对于每种颜色，每个前缀永远不会变为负数，这相当于确保分配给颜色的每个开头最终都与相同颜色的结尾按正确的顺序匹配。 

这表明使用深度奇偶性来控制分配。 当我们遍历字符串时，我们在处理每个字符之前跟踪当前深度。 如果我们根据深度是奇数还是偶数来交替分配，则同一嵌套级别的所有括号都会一致地变为相同的颜色。 由于嵌套结构与深度奇偶性完美对齐，因此每种颜色都继承了有效的非交叉结构。 

这是有效的，因为深度以结构化方式变化：每个“(”在其匹配的“)”减少深度之前增加深度，因此匹配对的两个端点在右括号决策之前共享相同的深度奇偶性。 因此两端的颜色相同，保持平衡。 

我们仍然可以自由地交换哪个奇偶校验映射到哪个颜色，因此通过平衡偶数层和奇数层之间的分配来最小化两个序列之间的最大深度。

 ## 算法演练

 我们在保持当前深度的同时扫描字符串。

1. 初始化深度 = 0 和一个空结果数组。 

深度表示我们在读取每个字符之前嵌套的深度。 
2. 对于字符串中的每个字符：

 我们根据当前的深度奇偶性来决定它的颜色。 
3. 如果字符是“(”，我们指定 color = height % 2，然后将深度增加 1。

 这可确保同一结构级别的所有空缺都进入同一组。 
4. 如果字符是“)”，我们首先将深度减1，然后指定颜色=深度% 2。 

关键是右括号与其相应的开口结构的深度相匹配，因此两个端点接收相同的颜色。 
5. 将分配的颜色存储在输出字符串中。 
6、处理完所有字符后，输出构造好的颜色字符串。 

工作原理：每对匹配的括号对应于从某个深度 d 开始并从 d+1 返回到 d 的深度行走的一段。 两个端点都使用相同的深度奇偶校验值 d 进行分配，因此两端的颜色相同。 这保证了每个匹配对都完全包含在一个子序列中。 由于嵌套保留在奇偶校验层中，因此每个颜色类形成一个有效的 RBS。 不会发生无效的交错，因为基于深度的分配尊重匹配的自然堆栈结构。

 ## 边缘情况

 一种边缘情况是完全扁平的结构，如“()()()”。 在这种情况下，深度奇偶性永远不会以产生分离的方式改变，因此所有括号最终可能会在一组中。 该算法可以正确处理此问题，因为允许使用单个有效 RBS，并为其他空组生成嵌套深度 1。 

另一个边缘情况是最大嵌套，如“((((...))))”。 在这里，每个级别都一致地交替颜色，并且每种颜色形成完美嵌套的独立链。 基于深度的分配确保没有对被跨颜色分割，因为每对的两个端点共享从其结构深度转换导出的相同奇偶校验分配。
