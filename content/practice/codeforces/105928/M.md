 ## 解决方案
 ## 问题理解

 向两名玩家提供有关桥牌类游戏的完整信息。 对于每种花色，每个玩家都已经确切地知道如果他们成为庄家并选择该花色，他们将赢得多少墩。 唯一的不确定性是投标过程，它决定了谁成为宣告者以及签订哪个合同。 

合约的等级由 1 到 7 级以及梅花、方块、红心、黑桃和无王牌的花色来定义。 等级高的总是打败等级低的，同一等级内，花色的顺序决定了实力。 玩家从迪卢克开始轮流叫牌。 每一次投标都必须严格优于前一次投标，否则就是非法的。 任何一个玩家都可以通过，一旦双方连续通过，拍卖就会结束，最后一个竞标者成为庄家。 如果没有人出价，结果为零。 

一旦选择了契约，宣告者必须至少获得等级加六墩。 最终得分取决于他们是成功还是失败、他们的脆弱性、合同以及成功或失败的幅度。 成功会带来技巧点数、合同奖金、可能的过度技巧奖励以及高等级的大满贯奖金的组合。 失败会根据技巧不足将惩罚转移给防御者，并根据漏洞的不同进行不同的调整。 

任务是在两名玩家都做出最佳出价后计算 Diluc 的最终分数，并且知道两名玩家都是完全理性的并且完全了解所有技巧结果。 

关键限制是最多有 104 个测试用例，并且每个测试仅包含恒定数量的数据：每个玩家每种花色有 5 个整数。 这立即意味着任何解决方案在每个测试用例中都必须是线性的或接近恒定的，因为任何比 O(t·70) 更差的事情都可以，但是任何涉及投标序列模拟或拍卖状态搜索的事情都是不必要的并且有风险。 

一个微妙的边缘情况是，两个玩家的最佳可能结果都是负面的。 在这种情况下，双方都希望拍卖在没有合同的情况下结束，收益为零。 总是强制签订合约的幼稚方法会错误地输出负值而不是 0。 

另一个边缘情况是，当迪卢克的最佳合同为正数时，而凯亚的最佳合同在担任宣告者时，会给迪卢克带来更糟糕的负分。 在这种情况下，即使迪卢克也有一个不错的选择，凯亚也会将拍卖强制纳入他自己的合同中，因为任何合同都可能出现出价过高的情况。 

## 方法

 对规则的强力解释会将整个投标过程模拟为游戏树。 每个状态将包含当前的最高出价、轮到谁以及前一个玩家是否通过。 在每个州，玩家可以通过或提出任何有效的更高出价。 每个花色层的树深度最多可达 35 个有意义的级别，并且分支涉及多个花色和级别。 尽管状态空间是有限的，但探索它会直接导致指数爆炸，因为每个玩家的选择都会影响所有后来的叫牌序列。 

关键的观察结果是，除了选择最终合同之外，投标系统不会引入隐藏的交互。 一旦确定了合同并指定了宣判员，分数就完全确定了。 由于双方都充分了解所有结果，因此竞价相当于在完全竞争下选择激活哪个终端合约。 

这将问题减少到对每个可能的合约进行两次评估，一次假设 Diluc 是声明者，一次假设 Kaeya 是声明者。 每次评估都会产生确定性分数。 之后，拍卖只是一场选择最终结果的竞赛，如果所有结果都是负面的，那么两个玩家都有可能选择通过。

因此，投标过程陷入了对终端公用事业的最大选择，迪卢克要么获得他的最佳宣告者分数，要么获得凯亚最佳宣告者分数的负数，如果双方都没有从强制合同中受益，则为零。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 全竞价状态搜索| 指数| 指数| 太慢了|
 | 直接评估所有合同 | O(70·t) | O(1) | O(1) | 已接受 |

 ## 算法演练

 ### ## 算法演练

 1. 对于担任庄家的固定玩家，迭代所有 35 种可能的合约，这些合约由 1 级到 7 级定义，并且花色从俱乐部到无王牌。 这已经足够了，因为每一次可能的拍卖都以其中一份合同结束。 
2. 对于每个合约，计算所需的墩数为级别加六，并将其与该花色中该玩家的已知墩数进行比较。 这决定了成败。 
3. 如果庄家成功，则使用与花色相关的公式计算特技点数，然后根据实际特技与所需特技之间的差值添加合同奖金、过度特技奖金以及大满贯奖金（如果级别为 6 或 7）。每个部分都是独立的，因此可以直接累积。 
4. 如果宣告者失败，则计算被欺骗的次数，并根据漏洞规则将其转换为防御者分数。 对于声明者来说，这个分​​数被视为负数，因为问题是零和的。 
5. 取 Diluc 作为庄家的所有合约中的最高分。 如果他赢得拍卖，这代表了他可以实现的最佳结果。 
6. 对作为宣告者的 Kaeya 重复相同的计算，以获得 Kaeya 的最佳得分。 
7. Diluc的最终答案是Diluc的最好成绩中的最大值，Kaeya最好成绩的否定，以及零，因为双方都可以理性地选择通过并在没有合同的情况下结束投标。 

核心不变量是，每个合法的投标序列必须在一份合同中终止，并且双方都可以通过继续出价来完全控制达成哪个终端合同，直到他们达到他们想要的结果或选择停止。 由于公用事业是在终端状态完全确定的，并且与到达它们所采取的路径无关，因此中间投标决策不会在选择最终合同之外创建额外的结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def score_declarer(tricks, need, level, suit, vuln):
    # suit index: 0 C, 1 D, 2 H, 3 S, 4 N
    if tricks >= need:
        y = tricks - need

        if suit in (0, 1):
            trick_points = 20 * level
            over = 20 * y
        elif suit in (2, 3):
            trick_points = 30 * level
            over = 30 * y
        else:
            trick_points = 30 * level + 10
            over = 30 * y

        if trick_points >= 100:
            contract_bonus = 500 if vuln else 300
        else:
            contract_bonus = 50

        slam = 0
        if level == 7:
            slam = 1500 if vuln else 1000
        elif level == 6:
            slam = 750 if vuln else 500

        return trick_points + contract_bonus + over + slam

    z = need - tricks
    if vuln:
        if z == 1:
            return -200
        if z == 2:
            return -500
        if z == 3:
            return -800
        return -(300 * z - 100)
    else:
        if z == 1:
            return -100
        if z == 2:
            return -300
        if z == 3:
            return -500
        return -(300 * z - 400)

def best(tricks, vuln):
    best_val = -10**18
    for level in range(1, 8):
        need = level + 6
        for suit in range(5):
            best_val = max(best_val, score_declarer(tricks[suit], need, level, suit, vuln))
    return best_val

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        v1, v2 = map(int, input().split())
        diluc = list(map(int, input().split()))
        kaeya = list(map(int, input().split()))

        d_best = best(diluc, v1)
        k_best = best(kaeya, v2)

        ans = max(d_best, -k_best, 0)
        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现将宣告者评分分离为单个函数，以便成功和失败案例保持对称且易于验证。 这`best`函数枚举所有合约而无需任何修剪，因为搜索空间是恒定且小的。 最后的组合步骤直接编码出价的零和结构：Diluc 要么发挥他的最佳合约，要么输给 Kaeya 的最佳合约，要么两者都通过。 

一个常见的实施陷阱是忘记过度戏法得分取决于花色，而不是合同级别。 另一个问题是合同奖金阈值处理不当，恰好为 100 个技巧点（包含在内）。 大满贯奖金也是独立的，必须在所有其他组成部分之后添加。

 ## 边缘情况

 一个关键的边缘情况是每份合同都会给两名球员带来负分。 在这种情况下，双方都理性地选择不强行签订合同，正确的输出为零。 该算法会处理这个问题，因为最终答案明确地在最大值中包含零。 

另一个边缘情况是，迪卢克的最佳合同为正，但从迪卢克的角度来看，仍然比凯亚的最佳合同更差。 的计算`max(d_best, -k_best, 0)`正确地捕捉了谁获得宣告者权利之间的竞争，确保 Kaeya 可以推翻 Diluc 的计划，如果他自己的最优合同产生了更强的结果。
