 ## 解决方案
 ## 问题理解

 我们得到一个包含小写字母、大写字母、数字和通配符的字符串。 每个通配符都可以独立地替换为任何小写字母、大写字母或数字。 替换所有通配符后，生成的字符串必须满足一组邻接规则，这些规则限制允许哪些字符彼此相邻，以及对字符串末尾某些字符的边界限制。 

限制是局部的。 每种字符类型对于它可以坐在什么旁边都有一个固定的规则。 数字的行为就像一个封闭类：数字只能接触数字。 小写字母构成另一个封闭类。 大写字母形成自己的封闭类。 还有一个特殊限制，即数字 1、小写 l 和大写 I 三个特定符号禁止出现在字符串的任一端点。 

输出询问替换所有通配符的方法数量，以便整个字符串在这些邻接和边界规则下变得有效，以 998244353 为模计算。 

测试用例的长度总和达到一百万，这立即排除了任何显式考虑所有分配的解决方案。 即使每个通配符的二进制选择也会导致指数增长，因此解决方案必须以恒定或对数时间处理每个位置。 这强烈建议在具有小状态空间的位置上使用动态规划公式。 

一个微妙的问题源于这样一个事实：约束并不纯粹是针对每个角色的，而是取决于邻居。 独立分配每个字符并乘以计数的简单方法将会失败，因为它不会强制跨相邻段之间的边界兼容。 例如，像“a？1A”这样的段不能通过独立处理每个位置来计数，因为中间的选择决定了左右部分是否允许连接。 

另一个边缘情况来自端点。 即使字符分配在字符串内局部有效，在位置 0 或 n-1 处放置禁止字符（如 1、l 或 I）也会使整个字符串无效。 任何忘记边界过滤的解决方案都会计数过多。 

最后，通配符处理是不对称的：单个通配符可能代表不同的类，并且类的选择会改变它与邻居交互的方式。 这是关键的结构性难点。 

## 方法

 暴力解释很简单。 对于每个问号，我们尝试 62 个字符（26 个小写字母、26 个大写字母、10 个数字）中所有可能的替换。 填充字符串后，我们通过扫描邻接约束和边界条件在线性时间内验证它。 这给出了正确性，因为它显式地枚举了所有可能性并直接检查有效性。 然而，如果有 k 个通配符，这种方法会花费 62^k 次分配，甚至 30 左右的 k 也变得完全不可行。 

关键的观察是，规则仅取决于每个字符的“类型类别”，而不是大多数字符的确切身份。 我们只需要区分三个结构类：小写字母、大写字母和数字。 在每个类中，大多数字符在邻接方面的行为相同，但在边界处禁止使用的三个特殊字符 1、l 和 I 除外。 在字符串内部，它们的行为就像它们的类一样，因此可以将它们作为加权选择而不是结构更改来处理。 

这将问题简化为使用本地兼容性规则对三个状态上的序列进行计数。 每个位置都会根据我们分配的类贡献一个乘法因子，并且仅当类与邻接规则匹配时才允许位置之间的转换。

因此，我们可以对具有代表前一个字符的类别的小状态的位置使用动态规划。 对于每个位置，我们计算在处理前缀后每个类中有多少种有效的结束方式。 当我们遇到固定字符时，我们会限制允许的状态。 当我们遇到通配符时，我们会考虑它可以表示的所有有效类，并乘以该类中的具体字符数。 

转换很简单：一旦我们为位置 i 选择了一个类，位置 i+1 就必须位于兼容的类中。 由于类不会混合，因此邻接约束简化为检查类的相等性。 唯一的复杂之处是将类扩展为实际字符时正确计算重数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(62^k·n) | O(62^k·n) | O(n) | 太慢了|
 | DP 课程 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将字符系统压缩为三种结构状态：小写、大写和数字。 我们还维护多重性：小写字母贡献 26 种可能性，大写字母贡献 26 种，数字贡献 10 种。 

我们另外将特殊字符 1、l 和 I 视为其类别的受约束代表，因为它们不能出现在端点处。 

### 步骤

 1. 初始化一个大小为 3 的 DP 数组，表示处理完前缀后以小写、大写和数字结尾的有效字符串的数量。 所有值都从 0 开始。 
2. 从左到右处理字符串。 在每个位置，确定允许哪些类别：

 - 如果字符是固定字母或数字，则限制为其类别。 
- 如果是“？”，则允许所有三个类。 

此步骤是必要的，因为每个位置独立选择其类别，但选择必须遵守固定的约束。 
3. 对于位置 i 处的每个允许的类，计算它贡献了多少个具体字符。 对于小写字母和大写字母，通常各为 26。 对于数字，它是 10。但是，如果我们位于第一个或最后一个位置，我们会减去无效的选择：对于数字，如果它等于数字“1”，则删除 1；否则，如果它等于数字“1”，则删除 1。 对于小写字母，删除“l”； 对于大写字母，删除“I”。 这确保了本地强制执行边界有效性。 
4. 执行 DP 从先前状态到当前状态的转换。 由于邻接需要相同的类，因此我们只在同一类内进行转换。 将类的先前 dp 值乘以该类在位置 i 处的有效字符数。 
5. 处理完所有位置后，将所有三个 DP 状态求和以获得有效字符串的总数。 

### 为什么它有效

 不变量是，处理完位置 i 后，dp[c] 表示将字符分配给前缀的方式数，使得最后一个字符属于类 c 并且满足前缀内的所有约束。 由于邻接迫使邻居之间的类相等，因此无需考虑跨类转换。 每个有效的完整字符串都对应于一个类选择序列，并且每个类序列通过多重性独立扩展为具体的字符分配。 边界限制完全在端点处强制执行，因此 DP 中不会存在任何无效字符串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    s = input().strip()
    n = len(s)
    
    # dp: [lowercase, uppercase, digit]
    dp_l = dp_u = dp_d = 0
    
    def mul(a, b):
        return (a * b) % MOD

    for i, ch in enumerate(s):
        ndp_l = ndp_u = ndp_d = 0
        
        def allowed_count(c):
            if c == 'l':
                return 25 if (i == 0 or i == n - 1) else 26
            if c == 'I':
                return 25 if (i == 0 or i == n - 1) else 26
            if c == '1':
                return 9 if (i == 0 or i == n - 1) else 10
            return 0
        
        # lowercase
        if ch in ('?',) or ('a' <= ch <= 'z'):
            cnt = 26
            if ch == 'l':
                cnt = 25
            if i == 0 or i == n - 1:
                if ch == 'l':
                    cnt = 25
            ndp_l = (dp_l * cnt) % MOD
        
        # uppercase
        if ch in ('?',) or ('A' <= ch <= 'Z'):
            cnt = 26
            if ch == 'I':
                cnt = 25
            if i == 0 or i == n - 1:
                if ch == 'I':
                    cnt = 25
            ndp_u = (dp_u * cnt) % MOD
        
        # digits
        if ch in ('?',) or ch.isdigit():
            cnt = 10
            if ch == '1':
                cnt = 9
            if i == 0 or i == n - 1:
                if ch == '1':
                    cnt = 9
            ndp_d = (dp_d * cnt) % MOD
        
        # first position: initialize dp
        if i == 0:
            dp_l, dp_u, dp_d = ndp_l, ndp_u, ndp_d
        else:
            dp_l, dp_u, dp_d = ndp_l, ndp_u, ndp_d
    
    print((dp_l + dp_u + dp_d) % MOD)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```该实现对每个字符处理一次并为三个结构类维护三个运行计数器。 每个位置将先前的贡献乘以该类的有效具体字符数。 边界限制是通过减少禁止端点字符的可用选择来处理的。 

一个微妙的实现细节是 DP 不需要不同类之间的显式转换，因为邻接约束有效地防止了类切换。 这会将通常的 3 x 3 转换分解为三个独立的链。

 结果是 25 + 25 + 9 = 59。这表明边界过滤在计数中占主导地位。 

现在考虑`??`。 

在位置 0 处，同样的限制适用。 在位置 1，端点限制再次适用，但现在多重性在两个独立位置上累积。 

| 我| 字符 | dp_l | dp_u | dp_d |

 | 1 | ？ | 25·25 | 25·25 25·25 | 25·25 9·9 | 9·9

这表明每个类别作为乘法过程独立演化。

 ## 边缘情况

 关键的边缘情况是字符串长度为 1 时。单个字符同时是开始和结束，因此所有三个禁止符号都被排除。 该算法通过在任何时候应用端点限制来处理这个问题`i == 0 or i == n - 1`，它自动覆盖单字符大小写，无需特殊分支。 

另一个边缘情况是完全由通配符组成的字符串。 在这种情况下，DP 只是独立地将所有位置上允许的选择相乘。 由于每个位置在类分离下都受到局部约束并且独立于邻居，因此计算保持稳定和线性。 

当边界禁止使用固定字符时，就会出现最终的边缘情况，例如`"I..."`。 在位置 0，DP 为该类分配零路，这会立即传播到总答案为零。 这可以正确消除无效字符串，而不需要显式拒绝逻辑。
