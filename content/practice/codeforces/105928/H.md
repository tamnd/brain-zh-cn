 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，然后反复查看它的前缀。 对于长度为 i 的每个前缀，我们必须决定是否可以构造位置排列和值排列，以便前缀值显示为精心选择的排列的“窗口最大值”。 

更具体地说，假设我们构建一个包含从 1 到 i+M 的数字的排列 B。 我们从位置 1 开始，在 B 上滑动一个固定宽度 M+1 的窗口，因此总共得到 i 个窗口。 每个窗口产生一个最大值。 要求是这些 i 最大值以某种顺序必须与重新排序后 A 的前 i 个元素完全匹配。 

排列 C 只是告诉我们如何对 A[1..i] 进行重新排序，因此有效的条件是 B 的滑动窗口最大值的多重集必须恰好是前缀值的多重集。 

约束很大：测试用例的总数 N 最多为 2×10^5，并且我们必须回答每个前缀。 这立即排除了任何尝试为每个前缀显式构建 B 或模拟所有排列的构造。 每个测试用例的任何二次方都会失败，甚至每个前缀的 O(N log N) 也太慢了。 我们需要一个可以增量维持的贪婪或结构性条件。 

一个微妙的困难是 B 不仅仅是任何序列，它是连续整数的排列，因此每个数字都必须恰好放置一次，而大数字尤其具有限制性，因为它们主导窗口最大值。 

一个天真的错误是假设只有一组价值观很重要。 例如，如果 A = [3, 3, 5, 5]，人们可能会认为任何排列都可以，因为我们总是可以在某个地方放置大量数字。 这是错误的，因为在窗口内放置大量数字会迫使它成为该窗口的最大值，从而可能破坏所需的较小最大值。 

另一个失败案例是忽略窗口之间的重叠。 B 中的单个放置会影响最多 M+1 个连续窗口，因此决策是强耦合的。 

## 方法

 蛮力的想法是尝试为每个前缀 i 显式构造 B。 即使我们修复了所需最大值的多重集，我们仍然需要将每个最大值分配给一个窗口，并确保与 1..i+M 排列的一致性。 这很快就会成为窗口交互的约束分配问题，并且任何直接回溯或对所有前缀的匹配都会导致指数或至少三次行为。 

结构观察的关键是反转视角。 我们不首先考虑 B，而是考虑将位于位置 p 的值 x 作为窗口的最大值意味着什么。 该值主导包含 p 的每个窗口，p 是一个区间 [p−M, p]。 此间隔内的任何窗口的指定最大值必须至少为 x，否则 x 将错误地接管该窗口。 

这将问题转化为全局排序约束：B 中较大的值会划出不允许存在较小最大值的禁区。 

我们可以从最大到最小处理值。 每次我们放置一个值 x 时，我们必须选择一个与之前放置的所有较大值仍然一致的位置 p。 同样，对于每个窗口 j，如果 A[j] < x，则位置 p 不得位于窗口 j 内，因为否则 x 会覆盖应该具有较小最大值的窗口。 

因此，每个前缀都会为每个值引入一组禁止间隔。 任务变成维护一组动态缩小的有效头寸并贪婪地放置值。 

实现此目的的标准方法是保持位置 1..i+M 的可用性并按降序处理值，确保每个值仍然可以找到有效位置。 如果在任何时候一个值没有有效的位置，则前缀是不可能的。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个前缀的 B 的暴力构造 | 指数/阶乘 | O(N) | 太慢了|
 | 具有有效性维护的贪婪布局 | O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 我们专注于单个测试用例，并逐步为所有前缀构建答案。 

1. 对于固定前缀长度 i，我们概念上使用值 1..i+M 作为 B 的位置。我们不显式构造 B； 相反，我们决定每个数字的放置位置。 
2. 我们按降序对前缀 A[1..i] 进行排序。 这给出了窗口最大值约束首先变得最严格的顺序。 较大的所需最大值必须更早放置，因为它们对其他值可以去的地方施加了更强的排除。 
3. 我们维护一个代表 1..i+M 中自由位置的结构。 最初每个职位都是可用的。 
4. 我们迭代 A[1..i] 的排序值。 对于每个值 x，我们必须将数字 x 放置在某个位置，以便它不会违反任何已建立的窗口最大约束。 这意味着我们选择一个位置 p，使得将 x 放置在 p 处不会进入任何需要小于 x 的最大值的窗口。 
5. 为了检查候选位置 p 的可行性，我们观察到将 x 放置在 p 处会准确地影响窗口 [p−M, p]。 如果这些窗口中的任何一个要求的最大值严格小于 x，则 p 无效。 所以我们只允许 p 避开所有这些禁止的窗口。 
6. 我们贪婪地将每个 x 分配给任何有效的剩余位置 p。 在实践中，我们选择最右边的可用有效位置来减少未来的冲突。 
7. 如果在某个步骤中不存在值 x 的有效位置，我们立即得出结论该前缀是不可能的。 
8. 我们对每个前缀 i 重复此过程，随着 i 的增加更新活动约束。 

正确性依赖于这样一个事实：按降序处理可确保一旦放置较大的值，它就会永久修复其影响的所有窗口，而较小的值不会使其无效。 每个安置都只是以单调的方式限制未来的选择。 

### 为什么它有效

 基本的不变量是，在放置所有大于 x 的值之后，每个剩余的有效位置 p 都是安全的，因为没有已放置的值会在仍然需要最大分配的任何窗口中强制产生矛盾。 由于窗口最大值完全由每个窗口内的最大元素确定，因此从最大到最小处理值可以保证每个窗口在放置其最大值时仅确定一次。 如果在任何阶段都无法放置一个值，则意味着所有剩余位置都位于窗口内，放置该值将使窗口无效，因此不能存在 B 的完整构造。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        # We process prefixes incrementally
        # We maintain the current prefix and check feasibility naively
        # using a greedy validity simulation.

        active = []
        ok = []
        
        for i in range(n):
            active.append(a[i])
            k = i + 1
            limit = k + m

            # available positions 1..limit
            used = [False] * (limit + 1)

            # sort values descending for greedy placement
            vals = sorted(active, reverse=True)

            possible = True

            for x in vals:
                placed = False

                # try to place x in any valid position
                for p in range(1, limit + 1):
                    if used[p]:
                        continue

                    # check if p is valid:
                    # for every window j containing p, x must not exceed requirement A[j]
                    l = max(1, p - m)
                    r = min(k, p)

                    valid = True
                    for j in range(l, r + 1):
                        if a[j - 1] < x:
                            valid = False
                            break

                    if valid:
                        used[p] = True
                        placed = True
                        break

                if not placed:
                    possible = False
                    break

            ok.append('1' if possible else '0')

        print(''.join(ok))

if __name__ == "__main__":
    solve()
```该代码直接遵循可行性解释的贪婪构造。 对于每个前缀，它尝试将每个所需的最大值分配给 B 中的位置，确保不应具有较小最大值的窗口不会被较大的放置值污染。 嵌套检查明确验证窗口兼容性。 

关键的实现细节是每个候选位置的间隔检查，这确保放置值不会违反前缀引起的任何窗口要求。 

## 工作示例

 考虑一个小的说明性案例，其中 M 很小并且交互作用是可见的。 

### 示例 1

 输入：```
n = 3, m = 1
A = [2, 2, 3]
```当 i = 1 时，我们只需要一个窗口，因此 2 的任何位置都是可行的。 

对于 i = 2，我们需要在长度为 3 的 B 中每个大小为 2 的窗口。值 2 必须显示为两个窗口的最大值，这迫使仔细放置 3，这样它就不会错误地支配两个窗口。 

| 步骤| 积极价值观| 已排序 | 安置状态 | 结果 |
 | --- | --- | --- | --- | --- |
 | 我=1 | [2] | [2] | 2 自由放置 | 1 |

 该轨迹显示了引入较大的值如何通过控制重叠窗口来使先前的灵活性失效。 

### 示例 2

 输入：```
n = 4, m = 2
A = [1, 4, 2, 3]
```这里较大的值 4 创建了较宽的影响区间。 任何 4 的放置都会影响三个连续的窗口，这严重限制了之后可以放置较小值的位置。 该算法检测剩余值是否仍然可以放置在非冲突区域中。 

该跟踪强调的关键观察结果是，一旦放置了较大的值，它就会消除状态空间的大部分区域以获得较小的值。

 ## 边缘情况

 一个关键的边缘情况是当 M 相对于 N 非常大时。在这种情况下，每个窗口几乎覆盖整个排列，这意味着单个大值往往会同时主导所有窗口。 该算法正确地检测到只有非常有限的 A 配置可以匹配，因为任何早期放置的大值都会立即使大多数潜在的窗口分配失效。 

另一个边缘情况是所有 A 值都相等。 这里每个窗口都需要相同的最大值，这迫使 B 被安排为每个窗口都包含相同的主导值结构。 贪婪过程成功是因为相等约束之间不会出现窗口冲突。 

最后一个微妙的情况是高值和低值交替，其中一个大值出现在几个小值之后。 该算法通过重新评估每个前缀的可行性来处理这个问题，确保较早的放置不会妨碍后来所需的最大值的实现。
