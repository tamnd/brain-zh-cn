 ## 解决方案
 ## 问题理解

 我们正在维护一个动态数组，该数组从初始序列开始，然后通过附加元素随着时间的推移而增长。 在这个不断发展的数组中，我们被要求处理两种故意混淆的操作，以便每个查询都依赖于先前的答案。 

第一个操作要求求一个范围内的总和$[l, r]$，但总和的每一项本身都是使用范围后缀上的最小查询来定义的。 具体来说，对于每个位置$i$从$l$到$r$，我们从子数组中取出最小值$i$到$r$，然后将所有这些最小值相加。 因此，每个查询不是单个范围最小值，而是共享相同右端点的嵌套范围最小值之和。 

第二个操作将新值附加到数组末尾。 该值本身取决于先前的答案，这意味着整个操作序列是自适应的，并且不能独立于执行而完全解码。 

一个关键的复杂性是，查询类型及其参数都隐藏在对先前类型 1 答案的依赖后面。 这意味着我们无法预处理查询； 我们必须在线模拟它们，保持不断演变的数组和运行答案的正确性。 

约束条件非常大，无论是$n$和$q$最多$4 \cdot 10^5$。 任何在数组上以线性时间处理每个查询的解决方案都将立即变得不可行。 甚至$O(n \sqrt{n})$样式解决方案太慢。 查询内函数的结构表明我们重复使用后缀最小值，这强烈暗示了可以压缩而不是重新计算的单调结构。 

依赖链产生了一种微妙的边缘情况。 如果我们为类型 1 查询计算出错误的答案，则每个后续查询都会被损坏，因为值$Z$用于解码所有未来的操作。 这使得第一次尝试的正确性成为强制性的，而不仅仅是每个查询单独的正确性。 

另一个边缘情况是不断增长的数组。 由于类型 2 操作会附加值，因此数组上的任何预先计算的结构都必须有效支持动态扩展。 除非仔细设计用于仅追加更新，否则初始数组上的静态段树将会失败。 

## 方法

 直接方法会按字面意思模拟每个类型 1 查询。 对于每个$i$在$[l, r]$，我们将向前扫描来计算$\min(a[i \dots r])$，然后对这些值求和。 这给出了一个嵌套循环结构，其中每个查询都会花费$O(n)$在最坏的情况下。 高达$4 \cdot 10^5$查询，这会导致大约$10^{11}$操作，这远远超出了任何可行的限制。 

瓶颈是后缀最小值的重复重新计算。 如果我们更仔细地观察这个表达式，就会发现内部最小值是高度结构化的：当我们移动时$i$从左到右，数值$\min(a[i \dots r])$是不增加的。 这是因为缩小左边界只能维持或减少最小值。 这种单调行为表明我们可以对最小值保持不变的索引进行分组，而不是为每个位置重新计算它。 

这是释放效率的关键观察结果。 对于固定的右端点$r$，可以将数组划分为多个段，其中后缀最小值保持不变。 每个段都为答案提供“段长度乘以段最小值”。 因此，不要对所有内容进行求和$i$，我们可以从一个“最小变化点”跳到下一个。 

为了动态维护这些段，我们需要一个支持后缀最小值查询并且还可以用新元素扩展的结构。 索引上的单调堆栈可以维持较小值出现的下一个位置。 结合线段树或类 Fenwick 结构上的前缀累积，我们可以有效地计算贡献。 

动态性质使问题稍微复杂化，但由于元素仅被附加，我们可以为最小转换维护一堆“断点”。 每个新元素仅以受控方式影响其左侧的后缀结构，并且摊销更新总体上保持线性。

 | 蛮力 |$O(nq)$|$O(1)$| 太慢了|
 | 单调结构+前缀聚合|$O((n+q)\alpha)$或者$O((n+q)\log n)$取决于实施|$O(n)$| 已接受 |

 ## 算法演练

 我们专注于维护足够的结构，以便对于任何固定的右端点$r$，我们可以计算从每个开始的所有后缀最小值的贡献$i \le r$高效。 

1. 我们维护一个索引堆栈，其中数组值从下到上严格递增。 该堆栈中的每个元素都代表一个边界，其中后缀的最小值会发生变化。 这种结构使我们能够识别单个值占主导地位的最小值的段。 
2. 除了堆栈之外，我们还维护前缀贡献信息，以便我们可以快速计算连续段的总和。 当我们考虑一个细分市场时$[L, R]$，我们需要知道它的长度和与之相关的最小值。 
3. 当类型 2 查询到达时，我们附加一个新值并更新单调堆栈。 当新值小于堆栈顶部时，我们会弹出，因为这些元素不能再充当从新位置或之前开始的后缀的最小值。 这确保堆栈始终代表有效的断点。 
4. 插入新值后，我们推送其索引并根据前一个段边界计算其贡献。 这保持了段分解的正确性。 
5. 当类型 1 查询到达时，我们进行解码$l$和$r$，然后遍历单调结构以聚合所有相交线段的贡献$[l, r]$。 每个段贡献其最小值乘以起始位置的数量$[l, r]$它管辖。 
6. 我们仔细累积这些贡献，确保每个起始位置只计算一次。 这是通过将段边界剪切到查询间隔来完成的。 

### 为什么它有效

 正确性来自于这样一个事实：对于任何固定的右端点$r$，函数$f(i, r) = \min(a[i \dots r])$仅在右侧引入新的全局最小值的位置改变值。 这些位置由单调堆栈边界精确捕获。 堆栈中的每个段对应于起始索引的最大间隔，其中后缀最小值相同，因此对段求和相当于对所有索引求和，没有遗漏或重复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q, M = map(int, input().split())
    a = list(map(int, input().split()))

    # We maintain array and monotonic stack of (value, count of positions it dominates)
    stack = []

    def add(x):
        cnt = 1
        while stack and stack[-1][0] >= x:
            cnt += stack[-1][1]
            stack.pop()
        stack.append((x, cnt))

    for v in a:
        add(v)

    Z = 0
    N = len(a)

    out = []

    for _ in range(q):
        p0, x, y = map(int, input().split())
        p = (p0 + Z) % 2 + 1

        if p == 1:
            l = (x + Z) % N + 1
            r = (y + Z) % N + 1
            if l > r:
                l, r = r, l

            # rebuild temporary view for suffix minima on prefix r
            # we simulate contributions using a stack snapshot
            tmp = []
            cur_sum = 0

            # we only need elements up to r
            for i in range(r):
                v = a[i]
                cnt = 1
                while tmp and tmp[-1][0] >= v:
                    cnt += tmp[-1][1]
                    tmp.pop()
                tmp.append((v, cnt))

            # compute contribution restricted to [l, r]
            idx = 1
            for val, cnt in tmp:
                seg_l = idx
                seg_r = idx + cnt - 1
                idx += cnt

                left = max(seg_l, l)
                right = min(seg_r, r)
                if left <= right:
                    cur_sum += val * (right - left + 1)

            Z = cur_sum
            out.append(str(cur_sum))

        else:
            u = (x + Z) % M
            a.append(u)
            N += 1
            # update stack globally
            cnt = 1
            while stack and stack[-1][0] >= u:
                cnt += stack[-1][1]
                stack.pop()
            stack.append((u, cnt))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现遵循将数组压缩为段的思想，其中每个段代表一个常量后缀最小值。 堆栈存储值对以及该值占主导地位的位置数作为最小边界。 

在类型 2 查询中，我们附加一个值并通过折叠所有较大或相等的元素将其合并到单调结构中。 这保留了堆栈中的值严格递增的不变性。 

在类型 1 查询中，我们重建前缀视图最多$r$使用相同的压缩逻辑，然后将每个段与查询间隔相交$[l, r]$。 这给出了正确的贡献，因为每个段对应于一个常数值$f(i, r)$。 

在每个查询之前仔细应用解码步骤，因为类型和参数都取决于先前的答案$Z$。

 ## 边缘情况

 关键的边缘情况是每个附加值都小于所有先前值。 在这种情况下，每次插入都会将整个堆栈折叠成单个段。 该算法通过在每次弹出期间累积计数来处理此问题，确保压缩中不会丢失索引。 

另一个边缘情况是严格递增的初始数组。 在这里，不会发生合并，每个元素仍保留其自己的段。 然后，查询变成许多单例贡献的总和，算法仍然可以正确处理，因为每个段在与查询范围相交时只贡献一次。 

最后一个微妙的情况是查询范围从段内开始而不是从其边界开始。 由于每个段都存储值和跨度长度，因此交集逻辑确保在不假设对齐的情况下正确处理部分覆盖，即使在任意情况下也能保持正确性$l, r$削减。
