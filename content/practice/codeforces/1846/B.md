 ## 解决方案
 ## 问题理解

 我们给出了一个非常小的棋盘的最终状态，总是 3 x 3，用于具有三个不同符号的简化井字游戏变体。 一名玩家放置 X，另一名玩家放置 O，第三名放置加号。 有些单元格可能仍然是空的。 棋盘已经完成配置，我们需要确定哪位玩家（如果有的话）已形成获胜线。 

获胜线是指三个相同的符号水平、垂直或对角地连续排列。 恰好存在一名获胜者，或者没有人获胜，在这种情况下，结果为平局。 我们还保证两个不同的符号永远不会在同一盘中同时形成获胜线。 

输入的测试用例数量非常多，多达一万块板，但每块板的大小都是恒定的。 这立即消除了除了每块板恒定时间之外的任何优化需求。 任何对每个测试用例进行超过 9 个细胞固定扫描的操作都已经是大材小用了。 

一个微妙的边缘情况来自空单元格和部分线条。 例如，像这样的行`X X .`尽管几乎形成了一场胜利，但这并不是一场胜利。 另一个是对角线检查，在粗心的实施中经常会被忽略。 例如，像这样的板```
X . .
. X .
. . X
```必须返回X。 

主要的实现陷阱是错误地假设计数符号就足够了。 例如，棋盘上有三个 X 并不能保证获胜，除非它们对齐。 

## 方法

 蛮力的想法是明确检查每个测试用例的每个可能的行。 由于棋盘只有 3 x 3，因此恰好有 8 条获胜线：3 行、3 列和 2 条对角线。 对于每一行，我们检查所有三个单元格是否包含相同的符号并且不为空。 这是每条生产线的恒定工作量，因此每个板都需要恒定的时间。 

一种更简单但结构性较差的方法是尝试三个细胞的所有子集并验证它们是否形成一条线。 这是不必要的，因为网格的几何形状是固定的并且是预先已知的。 这种方法仍然有效，但引入了冗余检查和更困难的实施。 

关键的观察结果是获胜线的集合是固定的并且很小。 这将问题从游戏模拟转换为直接模式匹配任务。 我们不是在模拟动作或检查有效性，只是识别静态模式。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（检查所有三元组）| O(t) 具有大常量或 O(t * 27 检查) | O(1) | O(1) | 已被接受但过于复杂 |
 | 最优（检查8行） | O(t) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将所有 8 条获胜线预先定义为扁平 3 x 3 网格上的索引三倍。 

1. 将每个棋盘转换为我们可以快速索引的结构，例如 9 个字符的列表。 这使得行检查变得简单，并避免重复的字符串索引逻辑。 此步骤很重要，因为它使行检查保持统一和可读。 
2. 定义 8 种获胜图案：三行、三列和两条对角线。 每个模式只是展平板上索引的三倍。 
3. 对于中的每个符号`X`,`O`， 和`+`，检查 8 个图案中是否有任何图案被该符号完全占据。 这是通过验证模式中的所有三个位置是否与符号匹配来完成的。 
4. 如果恰好有一个符号满足获胜条件，则输出该符号。 
5. 如果没有符号满足，则输出`DRAW`。 

我们分别显式检查所有三个符号的原因是，除了问题陈述之外，我们无法利用重叠保证。 尽管它保证不会同时获胜，但我们仍然必须独立验证每个获胜者。 

### 为什么它有效

 3 x 3 井字棋盘中的每种可能的获胜配置都与预定义的 8 条线之一完全对应。 没有其他几何排列可以形成胜利。 由于我们针对所有有效线测试所有符号，因此必须通过至少一项检查来检测任何获胜板。 相反，未获胜的棋盘不能满足任何全线条件，因此不能被错误地归类为获胜。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

LINES = [
    (0, 1, 2), (3, 4, 5), (6, 7, 8),  # rows
    (0, 3, 6), (1, 4, 7), (2, 5, 8),  # cols
    (0, 4, 8), (2, 4, 6)              # diagonals
]

def winner(board, ch):
    return any(board[a] == board[b] == board[c] == ch for a, b, c in LINES)

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        grid = []
        for _ in range(3):
            grid.append(input().strip())
        board = ''.join(grid)

        if winner(board, 'X'):
            out.append('X')
        elif winner(board, 'O'):
            out.append('O')
        elif winner(board, '+'):
            out.append('+')
        else:
            out.append('DRAW')

    print('\n'.join(out))

if __name__ == "__main__":
    solve()
```该解决方案将每个网格展平为长度为 9 的单个字符串，以便行检查变成简单的索引比较。 这`LINES`数组对所有可能的获胜配置进行编码，这消除了执行期间对坐标算术的任何需要。 

这`winner`函数是核心逻辑。 它扫描所有 8 行并检查所有三个位置是否包含相同的目标符号。 这是直接模式匹配，而不是搜索或模拟。 

检查的顺序仅在决胜局中重要，但该问题保证不会同时获胜，因此检查 X，然后检查 O，然后检查 + 是安全且确定的。

 ## 边缘情况

 空盘情况表明该算法不会根据符号计数推断获胜。 董事会`"..."`重复 3 次在 8 个模式中的任何一个中都不会产生匹配线，因此所有`winner`检查返回 false 并且输出是`DRAW`。 

仅对角获胜，例如`+O., O+O, .O+`确认对角线模式`(0,4,8)`正确包含并对称检查`(2,4,6)`。 如果没有这两种模式，大玩家的胜利就会被系统性地错过。 

专栏获胜如：```
X O .
X O .
X O .
```测试展平后垂直索引的一致性。 指数`(0,3,6)`正确地表示第一列，并且相等检查确保所有三行正确地贡献于同一行。
