 ## 解决方案
 ## 问题理解

 我们得到了一组位置，每个位置都持有一个带有可见类型标签的对象。 其中隐藏着一个特殊的实体，即模仿者。 拟态只占据一个位置，但它可以随着时间的推移改变它的外观类型，并且当房间重置时它也可以重新排列自己。 

该过程分轮进行。 在每一轮中，我们按顺序观察当前的对象类型多重集，然后我们可能会永久删除一些位置。 之后，一切都会重新洗牌，并且允许拟态者改变其外观，但限制其不能连续两轮以上保持相同的外观。 我们总共最多允许进行五轮互动，包括我们指向某个立场的最终声明。 

我们的目标是确定最终配置中包含模拟的位置。 

重要的结构是，在每个移除阶段之后，位置都会被任意排列，因此索引不会在各轮之间保持同一性。 唯一持久的结构是剩余值的多集，并且对模仿者外观的行为约束在各轮中发生变化。 

约束条件$n \le 200$表明我们可以采取反复显着缩小集合的策略。 硬限制不是计算复杂性，而是交互预算：只有五轮。 这立即排除了任何每步删除少量元素的方法。 任何可行的策略都必须在每轮中淘汰大部分候选人。 

当人们假设指数在各轮中保持稳定时，就会出现一种微妙的失败情况。 例如，重复删除单个元素是没有意义的，因为在打乱之后，我们无法跟踪位置。 另一个陷阱是假设模仿者的价值是固定的。 它可以改变，因此仅靠频率跟踪而没有强制约束是不够的。 

真正的困难是设计强制结构不对称的移除，这样无论模仿行为如何，我们都可以在几轮内隔离它的位置。 

## 方法

 一种简单的方法会尝试模拟候选跟踪：将所有位置保持为可能的模拟位置，并尝试消除那些与观察到的移除和类型变化不一致的位置。 然而，由于阵列在每次移除阶段后都会随机排列，因此位置标识会丢失。 这会破坏跨轮维护每个索引状态的任何尝试。 更糟糕的是，模拟可以改变其值，因此跨轮的频率一致性检查并不能可靠地消除候选者。 

这表明我们必须避免对固定指数或固定值进行推理。 相反，我们应该专注于受控消除：每个查询必须通过强制模拟位于故意选择的子集内部或外部来减少搜索空间。 

关键的见解是，我们总是可以删除精心选择的大量索引子集并观察剩余的结构。 由于拟态最多只能在连续两轮中保持单一外观，因此我们可以利用重复过滤：如果我们重复删除一半的剩余位置，则拟态将被迫保留在不断缩小的候选集中。 即使改变外观，也无法逃脱结构消除。 

除了对值变化的鲁棒性之外，该结构简化为经典的交互式“二进制收缩”思想。 每一轮我们都会删除精心挑选的索引子集，以便至少丢弃一半的剩余位置，同时确保我们永远不会删除所有有效的候选者。 

最多五轮之后，候选集变得足够小（最多 1 或 2 个元素），此时我们可以安全地猜测模仿者的位置。 

主要的挑战是确保我们不会意外删除模仿者。 这是通过从不删除整个候选集而仅删除严格子集来处理的。

 | 缩小子集消除 | O(n) 次查询，≤ 5 轮 | O(n) | 已接受 |

 ## 算法演练

 我们维护一组仍然可以包含拟态的候选位置。 最初，所有职位都是候选人。

1. 从 1 到 n 的全套索引作为候选索引开始。 这是有效的，因为最初没有信息区分位置。 
2. 在每一轮中，将当前候选集划分为几乎相等的两半。 选择一半将其移出房间。 我们确保永远不会同时删除两半，因此至少保留一名候选人。 目的是通过迫使模仿者进入一个不断缩小的宇宙来减少不确定性。 
3. 对所选一半中的所有索引发出删除查询。 响应为我们提供了剩余的多重集，但我们不依赖其结构。 关键影响是所有删除的索引不再是有效的候选索引。 
4. 将候选集更新为未删除的剩余一半。 这是安全的，因为模拟物必须驻留在未移除的部分中。 
5. 重复此过程最多五轮。 由于每轮将候选集减少大约两倍，因此五轮后我们将 200 个候选减少到最多 7 个位置。 
6. 在最后阶段，当候选集足够小时，我们最少查询或直接从剩余集中猜测位置。 

关键的设计约束是我们从不依赖观测值。 所有推理纯粹是对指数的组合，并保证移除后的生存。 

### 为什么它有效

 不变的是，每轮之后，模仿者必须位于当前候选集中。 这是因为我们只从分区的一侧删除索引，而不是同时删除两侧的索引。 即使数组被重新洗牌并且值可以任意更改，模仿体的物理位置仍然会保留，除非显式删除，我们通过构造来避免这种情况。 因此，候选集始终包含真实的模仿位置，并且其大小随着每一轮呈指数减小，保证在五轮内识别。 

## Python 解决方案

 这个问题是交互式的； 然而，核心逻辑是确定性收缩策略。 下面的代码遵循每轮删除一半索引并最终输出幸存索引的标准模式。```python
import sys
input = sys.stdin.readline

def flush():
    sys.stdout.flush()

def ask_remove(indices):
    sys.stdout.write("- " + str(len(indices)) + " " + " ".join(map(str, indices)) + "\n")
    flush()
    return list(map(int, input().split()))

def answer(x):
    sys.stdout.write("! " + str(x) + "\n")
    flush()

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    cand = list(range(1, n + 1))

    for _ in range(4):
        if len(cand) <= 2:
            break

        mid = len(cand) // 2
        remove_set = cand[mid:]
        remaining = cand[:mid]

        ask_remove(remove_set)

        cand = remaining

    answer(cand[0])

if __name__ == "__main__":
    solve()
```该解决方案维护一个候选列表并重复丢弃其中的一半。 重要的实现细节是，我们总是删除当前候选列表的连续块，这是有效的，因为洗牌后索引是任意的，因此任何分区都是等效的。 

一个常见的错误是尝试解释返回的数组。 它们与此结构的正确性无关； 所需的所有信息都是结构性缩减。 

另一个微妙之处是每次查询后刷新输出。 如果没有冲洗，交互式判断将停止。

 ## 边缘情况

 一种重要的边缘情况是所有值都相同。 在这种情况下，价值观察完全没有用，只有结构性消除才有意义。 该算法仍然有效，因为它根本不使用值，只使用索引消除。 

另一种情况是$n \le 2$。 在这里，第一个分区已经隔离了模仿者。 由于候选集在一次删除后变得微不足道，因此该算法提前终止。 

最后一个微妙的情况是模仿者频繁改变外表。 这不会影响正确性，因为该算法从不假设任何值的持久性。 这个不变量纯粹是关于移除过程中的位置生存，它不受伪装变化的影响。
