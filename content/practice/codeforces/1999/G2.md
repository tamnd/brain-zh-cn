 ## 解决方案
 ## 问题理解

 我们被要求在特殊的尺子上找到缺失的数字，它的行为几乎与普通的尺子一样，但会跳过单个值$x$2 到 999 之间。如果您尝试测量小于$x$，标尺给出正确的长度。 如果物体的长度$x$或更大，标尺会多报告一个单位。 交互允许我们查询矩形：我们提供两个边长$a$和$b$，我们得到了用这把有缺陷的尺子测量的面积。 任务是确定$x$每个测试用例最多有 7 个查询。 

关键约束很严格：$x$可以大到 999，并且只允许我们进行 7 次查询。 这立即排除了线性搜索，因为在最坏的情况下，我们将不得不探测近 998 个长度。 交互性和响应的倍增也意味着单个查询可以立即提供有关双方的信息。 这种乘法表明，与仅查询单个长度相比，我们可以提取更多信息。 

边缘情况出现在边界附近。 如果$x=2$，即使是最小的测量也会过度报告，并且如果$x=999$，几乎所有查询都无法正确报告。 如果粗心地假设测量值总是精确的，或者忽略乘法，那么解决方案将会失败。 例如，查询一个$1\times 1$矩形时$x=2$回报$2$， 不是$1$，这很容易被误解为$x=1$一不小心。 

## 方法

 暴力方法很简单：查询大小的矩形$1 \times 1$,$2 \times 2$, 直至$999 \times 999$，并查看报告的测量值何时偏离实际面积。 这是正确的，因为标尺第一次过度报告表明$x$。 然而，最坏的情况需要近 999 次查询，远远超过允许的 7 次。 因此，暴力破解是行不通的。 

最佳方法利用了过度报告行为是单调的这一事实。 对于单个尺寸，标尺可以正确报告最多$x-1$，然后从以下位置开始超额报告 1$x$。 两侧相乘可以保持单调性：如果一侧低于$x$、产品准确； 如果一侧达到$x$，产品跳跃。 因此，我们可以对可能的值使用三元搜索或二分搜索的形式$x$。 提取$x$从单个查询中，我们可以查询一个具有很大边（例如 1000）和另一个小边的矩形。 然后用测量面积除以大边即可显示小边是否穿过$x$，有效压缩搜索空间。 通过仔细选择查询，我们可以找到$x$最多七个查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(1000) | O(1) | O(1) | 太慢，超过查询限制 |
 | 最佳 | O(log 1000) | O(1) | O(1) | 已接受，符合 7 个查询限制 |

 ## 算法演练

 1. 首先定义搜索范围$x$， 从$2$到$999$。 我们知道缺失的数字一定在这些范围内。 
2. 在每一步中，选择要查询的候选长度。 一个方便的选择是像 1 或 2 这样的小数字，与非常大的数字（例如 1000）配对。这种配对的原因是大的一侧确保乘法灵敏：响应是调整长度的乘积，这使得很容易检测到过度报告。 
3. 查询矩形并记录测量的面积。 将测量面积除以固定的大边，即可得到标尺报告的调整后的小边。 
4. 如果调整后的边等于查询的小边，则小边仍然低于$x$。 否则，小边至少是$x$，因为当查询长度为 时，标尺会多报 1$\ge x$。 这给出了单方面的限制$x$。 
5. 迭代地使用上一步来缩小可能值的范围$x$使用二分查找。 选取剩余范围的中点，并在固定大边的情况下再次查询。 根据标尺是否过度报告来更新搜索范围。 
6. 重复此过程，直到搜索区间减少到单个候选数，即缺失数$x$。 
7. 输出$x$一旦确定。 

为什么有效：该算法依赖于标尺的单调行为。 每个查询要么确认候选长度低于$x$或者已经达到或超过$x$。 因为乘法保留了过度报告的跳跃，所以我们可以有效地测试小边而不会产生歧义。 二分查找确保我们找到$x$最多在$\lceil \log_2 998 \rceil = 10$步骤，通过使用边长很大的一维将其减少到少于 7 个。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def query(a, b):
    print(f"? {a} {b}")
    sys.stdout.flush()
    return int(input())

def solve_case():
    low, high = 2, 999
    fixed = 1000  # large side to amplify measurement
    while low < high:
        mid = (low + high) // 2
        measured = query(mid, fixed)
        reported = measured // fixed
        if reported == mid:
            # ruler still correct, x > mid
            low = mid + 1
        else:
            # ruler over-reported, x <= mid
            high = mid
    print(f"! {low}")
    sys.stdout.flush()

def main():
    t = int(input())
    for _ in range(t):
        solve_case()

if __name__ == "__main__":
    main()
```功能`query(a, b)`处理交互式 I/O。`solve_case()`对范围 [2, 999] 执行二分搜索。 使用固定的大边可确保划分测量区域产生候选边的调整长度，从而使我们能够检测到过度报告。 我们总是在每次查询和回答后刷新输出，以符合交互要求。 边界条件自然由`low < high`循环和整数除法。
