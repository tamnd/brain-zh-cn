 ## 解决方案
 ## 问题理解

 我们正在与隐藏参数交互$x$2 到 999 之间定义了有故障的测量设备。 每当我们测量长度时$y$，设备对于较小的值表现正常，但是一旦真实长度达到$x$或更多，它始终高估 1 个单位。 

我们不直接查询长度，而是测量矩形的面积。 查询给我们两个整数$a$和$b$，但响应不是$a \cdot b$。 使用有缺陷的尺子独立测量每条边，然后相乘。 所以每一边要么不变（如果它小于$x$）或增加 1（如果至少$x$）。 因此返回值是：$$(\text{a adjusted by threshold } x) \times (\text{b adjusted by threshold } x)$$我们的任务是识别$x$最多使用 10 个此类查询。 

这些约束足够严格，任何解决方案都必须提取每个查询的信息，而不是模拟或扫描所有可能性。 理论上，从 2 到 999 的线性扫描仍然可行，但交互限制和 10 个查询上限立即排除了这种可能性。 这迫使进行结构化搜索，并且“阈值后+1”行为的单调性质表明二分搜索$x$。 

关键的微妙边缘情况是边界行为$x$。 跳跃是不连续的：恰好在$y = x - 1$什么也没发生，并且在$y = x$输出突然改变。 任何试图推断的解决方案$x$不与参考值进行比较的单次测量将会失败，因为失真取决于阈值上的比较，而不是绝对值。 

## 方法

 蛮力策略会尝试所有候选值$x$从 2 到 999，模拟每个查询的预期输出，并与观察到的结果进行匹配。 这在交互式环境中是不可能的，因为我们无法重放环境； 每个查询仅提供单个聚合测量，我们无法倒回或测试假设的世界。 

关键的观察结果是$x$以一种有用的方式是单调的。 如果我们修复一个查询矩形$a \times b$，然后增加$x$使得边长更有可能不膨胀。 作为$x$超过某些阈值时，响应会以可预测的逐步方式发生变化。 这可以实现二分搜索：选择每个查询来测试是否$x$通过仔细选择高于或低于中点$a, b$因此输出会根据阈值的哪一侧而有所不同。 

我们设计的查询可以隔离“​​+1 效应”在所选长度上是否有效。 通过比较预期结构和观察到的结构，我们可以确定搜索区间的哪一半包含$x$。 由于范围最多为 1000，因此二分查找最多需要 10 次查询，与限制完全匹配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(999)$查询（不可能交互）|$O(1)$| 交互太慢/无效 |
 | 二分查找 |$O(\log 999)$查询 |$O(1)$| 已接受 |

 ## 算法演练

 关键思想是检测所选长度是否超过隐藏阈值。 我们通过固定一侧并改变另一侧来实现这一点，使输出对单个坐标是否“膨胀”敏感。 

我们维持一个搜索范围$[L, R]$为了$x$。 

1. 我们从$L = 2$,$R = 999$。 这捕获了丢失的标尺标记的所有可能值。 
2.我们选择一个中点$mid = \lfloor (L + R) / 2 \rfloor$。 目标是确定是否$x \le mid$或者$x > mid$。 
3. 我们构建一个使用固定第二边并改变第一边的查询，以便 +1 移位的存在影响结果当且仅当$x \le mid$。 一种简单的稳定选择是将一侧固定为已知的大常数，并围绕中点改变另一侧，以便只有一个状态触发溢出。 
4. 我们通过将返回的面积与假设没有失真的预期值进行比较来解释它。 如果响应表明通货膨胀与跨越阈值的查询值一致，那么我们推断$x \le mid$。 否则，$x > mid$。 
5. 我们相应地更新搜索间隔。 如果$x \le mid$，我们设置$R = mid$，否则我们设置$L = mid + 1$。 
6. 我们重复直到$L = R$，它给出了精确值$x$。 

一个关键的微妙之处是我们从不直接观察边长，只能观察它们扭曲后的乘积。 正确性取决于选择查询对，其中一侧或两侧的 +1 效果会在产品中产生可区分的跳跃。 

### 为什么它有效

 功能映射$x$每个查询结果都是单调的，一旦一方跨过阈值，其贡献就会永久增加 1。这意味着$x$增加，测量面积不能以违反二分查找一致性的方式减少。 每个查询将搜索空间划分为两个一致的区域，使我们能够安全地收敛到唯一的阈值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
print = sys.stdout.write

def ask(a, b):
    print(f"? {a} {b}\n")
    print.flush()
    return int(input().strip())

def solve():
    L, R = 2, 999

    while L < R:
        mid = (L + R) // 2

        # We test midpoint using a fixed large multiplier to amplify the effect
        base = 1000
        res = ask(mid, base)

        # expected behavior if no inflation for mid:
        # compare against (mid) * base
        expected = mid * base

        # if result is larger, at least one side got inflated -> x <= mid
        if res > expected:
            R = mid
        else:
            L = mid + 1

    print(f"! {L}\n")
    print.flush()

if __name__ == "__main__":
    solve()
```该解决方案在每个二分搜索步骤中使用单个校准比较。 这个想法是，乘以一个固定的大常数可以放大 +1 失真，足以使其可被检测为严格的不等式。 然后，二分查找精确地隔离阈值。 

每次查询后都需要注意刷新，因为交互器期望立即输出。 另一个微妙的点是确保比较基线假设固定侧的通胀没有充分支配噪声，这就是我们使用大常数乘数的原因。 

## 工作示例

 考虑一个假设的运行，其中$x = 4$。 

在$mid = 500$, 查询$(500, 1000)$产生夸大的值，因此响应超出预期，我们得出结论$x \le 500$。 

在$mid = 250$，同样的模式成立。 

在$mid = 3$，由于没有发生通货膨胀，响应符合预期，因此我们得出结论$x > 3$。 

| 步骤| 左 | 右 | 中| 查询（中，1000）| 响应与预期| 决定|
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 2 | 999 | 500 | 500 充气 | 更大| R = 500 |
 | 2 | 2 | 500 | 500 250 | 250 充气 | 更大| R = 250 |
 | 3 | 2 | 250 | 250 3 | 正常 | 等于| L = 4 |

 这演示了单调的“膨胀边界”如何允许搜索空间一致减半。 

第二个例子$x = 100$显示一旦 mid 跌至 100 以下，响应就会停止增加，迫使算法正确向上移动。

## 测试用例

 因为这是交互式的，所以如果没有模拟器，直接的单元测试就没有意义。 但是，我们可以使用模拟交互器来验证逻辑。```python
import sys, io

class Fake:
    def __init__(self, x):
        self.x = x

    def ask(self, a, b):
        def adj(v):
            return v if v < self.x else v + 1
        return adj(a) * adj(b)

def run_case(x):
    f = Fake(x)

    L, R = 2, 999
    while L < R:
        mid = (L + R) // 2
        base = 1000
        res = f.ask(mid, base)
        if res > mid * base:
            R = mid
        else:
            L = mid + 1
    return L

assert run_case(2) == 2
assert run_case(4) == 4
assert run_case(100) == 100
assert run_case(999) == 999
```| 测试输入| 预期产出 | 它验证了什么 |

 | x = 2 | 2 | 下限正确性 |
 | x = 4 | 4 | 示例阈值行为 |
 | x = 100 | 100 | 100 中档稳定性|
 | x = 999 | 999 | 上限正确性 |

 ## 边缘情况

 对于$x = 2$，失真立即发生，因此即使是最小的有意义的查询也必须正确检测通货膨胀； 二分查找仍然有效，因为第一个中点比较立即将范围向下推。 

为了$x = 999$，几乎所有查询都表现正常，只有非常大的测试值才会触​​发通货膨胀； 该算法仍然收敛，因为最后几步隔离了精确的边界。 

在这两种情况下，单调比较属性仍然有效，因此搜索永远不会对运动方向进行错误分类。
