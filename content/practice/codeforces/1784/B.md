[CF 1784B - 信件交换](https://codeforces.com/problemset/problem/1784/B)

 **求解时间：** 2m 1s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 每个人都以三个字母开头，选自`w`,`i`， 和`n`。 所有的人加起来，正好有`m`每封信的副本，因此全球供应已经平衡。 唯一的问题是这些信件在个人之间分布不均。 

交换选择两个人。 每个人都给出一封信并收到对方的一封信。 经过一系列的交换后，每个人最终都必须恰好持有一个`w`， 一`i`，和一个`n`。 在所有有效的解决方案中，我们必须使用尽可能少的交换次数输出一个解决方案。 

思考一个人最有用的方法不是通过字符串中字母的顺序，而是通过计数。 例如，`"wwi"`意味着这个人有两个`w`， 一`i`，并且没有`n`。 这样的人有一个盈余`w`并且缺少一个`n`。 

这些限制立即排除了任何基于搜索的方法。 一个测试用例最多可以包含`10^5`人，所有测试用例的总和也是`10^5`。 任何重复扫描所有寻找贸易伙伴的人的算法很容易变得二次。 我们需要接近线性时间的东西。 

一个微妙的一点是交流必须最少。 产生任何有效的重新分配是不够的。 我们必须利用赤字和盈余的结构，以便每一次交换都能尽可能多地修复。 

一种容易被忽视的边缘情况是不需要交换的情况。 

输入：```
2
nwi
inw
```两人都已经各有一封信了。 正确答案是：```
0
```盲目地将每个人放入交易结构而不检查它们是否已经平衡的实现可能会产生不必要的交换。 

另一个重要的情况发生在两个人可以直接解决彼此的问题时。 

输入：```
2
wwi
inn
```第 1 个人有一个额外的`w`并且缺乏`n`。 第2个人有一个额外的`n`并且缺乏`w`。 一次交换就足够了：```
1
1 w 2 n
```任何使用两个交换的解决方案都是有效的，但不是最小的。 

最后一个棘手的情况是三循环。 

输入：```
3
wwi
iin
nnw
```赤字形式：`wwi`： 额外的`w`, 需要`n`

`iin`： 额外的`i`, 需要`w`

`nnw`： 额外的`n`, 需要`i`没有一对可以直接修复彼此。 一个粗心的贪婪者如果只寻求相互修复，就会陷入困境。 最优解需要两次交换。 

## 方法

 蛮力策略会反复寻找两个人的交换可以改善情况。 由于每个人可能需要与许多其他人进行比较，因此这很快就会变得昂贵。 和`10^5`人，甚至一个`O(m²)`方法需要围绕`10^10`的操作，这是完全不可行的。 

关键的观察结果是只有三种可能的字母类型：`w`,`i`， 和`n`。 一个人完全可以通过这三个字母的数量来描述。 由于每个计数都介于`0`和`3`总数始终是`3`，只有十种可能的计数模式。 

对于每个人，我们可以识别哪些字母是多余的，哪些字母是缺失的。 如果某人有一封信的两份或三份副本，他们可以捐赠该信。 如果某人有一封信的零份，那么他们就需要这封信。 

假设一个人有剩余`w`并且缺乏`i`，而另一个有盈余`i`并且缺乏`w`。 一个交易所可以立即修复这两项赤字。 这种交换始终是最佳的，因为单个操作可以同时解决两个丢失的字母。 

在执行每一次可能的直接交换之后，唯一剩下的不平衡在三种字母类型之间形成有向循环。 由于只有三个字母，因此剩余的每个循环的长度为三：`w → i → n → w`或者`w → n → i → w`一个涉及三个人的循环正好需要两次交换。 这也是最优的，因为还存在三个赤字，而一次交换最多可以消除两个赤字。 

字母类型的数量极少，使我们能够将人员存储在按以下索引的存储桶中`(surplus letter, missing letter)`。 那么每次操作就变成了桶之间的恒定时间移动。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(平方米) | O(米) | 太慢了 |
 | 最佳 | O(米) | O(米) | 已接受 |

 ## 算法演练

 让字母索引为：`0 = w`,`1 = i`,`2 = n`。 

对于每个人，计算每个字母的数量。 

创建存储桶`pos[a][b]`， 在哪里`a`是一个多余的字母并且`b`是一封丢失的信。 如果一个人有多个多余的副本和多个丢失的字母，那么他可能会出现在多个桶中。 

对于每个存储桶条目，我们存储该人的索引。 

### 1. 对所有人进行分类

 对于每个人，找到所有计数大于 1 的字母以及所有计数为零的字母。 

对于每对`(surplus, missing)`，将该人放入桶中`pos[surplus][missing]`。 

一个有数数的人`(3,0,0)`贡献两个桶条目，因为他们可以捐赠相同的剩余字母来满足两个不同的缺失字母。 

### 2. 执行所有直接交换

 对于每对有序的不同字母`(a,b)`，重复匹配一个人`pos[a][b]`与一个人从`pos[b][a]`。 

第一个人送信`a`，第二个给出字母`b`。 

两个人都立即修复了一封丢失的信件，因此一次交换就解决了两个赤字。 

将两个参与者从他们的存储桶中删除并记录操作。 

### 3.解决三循环

 当所有直接匹配都用尽后，只剩下循环依赖。 

考虑一个循环：`a → b`,`b → c`,`c → a`从其中选择一个人`pos[a][b]`, 一个来自`pos[b][c]`，以及一个来自`pos[c][a]`。 

执行：

 1、第一人和第二人之间的交流。 
2、第一人和第三人之间的交流。 

这两次交换消除了整个循环。 

重复此操作，直到相应的桶变空。 

对两种可能的循环方向都执行此操作。 

### 4.输出所有记录的交易

 记录的操作数量很少，因此将其打印出来，然后进行交换。 

### 为什么它有效

 每个赤字对应于从多余字母到缺失字母的有向边。 

之间的直接交换`a→b`和`b→a`使用一项操作删除两条相对的边。 没有任何解决方案可以做得更好，因为一个交易所无法消除两个以上的赤字。 

删除所有相反的对后，每个剩余的顶点都具有相同的传入和传出不平衡性，因为每个字母的总数已经全局正确。 由于只有三种字母类型，剩余的图只能由有向 3 圈组成。 

定向 3 循环包含三个赤字。 一次交换最多可以消除两个赤字，因此至少需要两次交换。 上面的结构正好使用了两个。 

由于每个操作对于其解析的结构都是最佳的，因此交换的总数是最少的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    mp = {'w': 0, 'i': 1, 'n': 2}
    rev = ['w', 'i', 'n']

    out = []

    for _ in range(t):
        m = int(input())

        pos = [[[] for _ in range(3)] for _ in range(3)]

        for idx in range(1, m + 1):
            s = input().strip()

            cnt = [0, 0, 0]
            for ch in s:
                cnt[mp[ch]] += 1

            surplus = []
            missing = []

            for c in range(3):
                if cnt[c] > 1:
                    surplus.extend([c] * (cnt[c] - 1))
                elif cnt[c] == 0:
                    missing.append(c)

            for a in surplus:
                for b in missing:
                    pos[a][b].append(idx)

        ans = []

        def direct(a, b):
            while pos[a][b] and pos[b][a]:
                x = pos[a][b].pop()
                y = pos[b][a].pop()
                ans.append((x, rev[a], y, rev[b]))

        for a in range(3):
            for b in range(a + 1, 3):
                direct(a, b)

        cycles = [
            (0, 1, 2),
            (0, 2, 1),
        ]

        for a, b, c in cycles:
            while pos[a][b] and pos[b][c] and pos[c][a]:
                x = pos[a][b].pop()
                y = pos[b][c].pop()
                z = pos[c][a].pop()

                ans.append((x, rev[a], y, rev[b]))
                ans.append((x, rev[a], z, rev[c]))

        out.append(str(len(ans)))
        for x, ca, y, cb in ans:
            out.append(f"{x} {ca} {y} {cb}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```分类阶段将每个人转换为多余和缺失的字母。 一个有数数的人`(2,1,0)`贡献一个存储桶条目，而一个人则计数`(3,0,0)`贡献两个存储桶条目，因为最终必须传输两个副本。 

直接匹配阶段是最小化论证的核心。 每当存在相反的赤字时，一个交易所就会同时解决这两个问题。 推迟这样的比赛绝对没有帮助。 

循环阶段仅在所有相反的对消失后运行。 此时剩余结构被迫进入 3 个周期。 该实现仅使用两个记录的操作一次删除一个完整的周期。 

一个常见的错误是只存储一个`(surplus, missing)`每人一对。 有人拿着`"www"`有两份多余的副本，并且缺少两个不同的字母。 两种赤字都必须得到体现。 所有多余和缺失字母的嵌套循环可以正确处理这个问题。 

## 工作示例

 ### 示例 1

 输入：```
3
inn
nww
wii
```初始桶：

 | 人 | 类型 |
 | --- | --- |
 | 1 | n→w |
 | 2 | w→i |
 | 3 | 我→n |

 不存在相反的对。 

检测到循环：`w→i → i→n → n→w`选择：

 | 桶| 人 |
 | --- | --- |
 | w→i | 2 |
 | 我→n | 3 |
 | n→w | 1 |

 操作：

 | 步骤| 交流 |
 | --- | --- |
 | 1 | 2 给出 w，3 给出 i |
 | 2 | 2 给出 w，1 给出 n |

 两次交换后循环消失。 

此示例说明了为什么仅直接匹配是不够的。 其余结构是纯三循环。 

### 示例 2

 输入：```
4
win
www
iii
nnn
```分类：

 | 人 | 类型 |
 | --- | --- |
 | 2 | w→i 和 w→n |
 | 3 | i→w 和 i→n |
 | 4 | n→w 和 n→i |

 直接匹配：

 | 桶对| 交流 |
 | --- | --- |
 | w→i 与 i→w | 2 ↔ 3 |
 | w→n 与 n→w | 2 ↔ 4 |
 | i→n 与 n→i | 3 ↔ 4 |

 总交换次数 = 3。 

该轨迹显示了一种情况，其中每个缺陷都可以通过直接配对来解决，并且不需要循环处理。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(米) | 每个存储桶条目都会被插入和删除固定次数 |
 | 空间| O(米) | 存储桶和答案存储包含 O(m) 个条目 |

 桶条目数与缺失字母数成正比，最多为`2m`。 每个条目都参与一个匹配过程。 由于总和为`m`所有测试用例最多是`10^5`，该算法很容易满足限制。

 ## 边缘情况

 考虑：```
2
win
win
```没有人有盈余或赤字。 没有存储桶接收任何条目。 直接匹配阶段和循环阶段都不执行任何操作，产生零交换。 

考虑：```
2
wwi
inn
```桶包含`w→n`和`n→w`。 直接阶段立即匹配它们并输出一个交换。 由于单个操作可以修复这两个缺陷，因此这是最佳的。 

考虑：```
3
wwi
iin
nnw
```桶包含`w→n`,`i→w`， 和`n→i`。 不存在相反的对，因此直接相位无济于事。 循环阶段识别唯一的三循环并使用两次交换来解决它。 由于还存在三个赤字，而一次交换最多可以消除两个，因此最少可能进行两次操作。 

最后，考虑：```
3
www
iii
nnn
```每个人贡献两个桶条目。 第一个人必须捐赠两份单独的`w`字母，没有一个。 代表所有盈余缺失组合可确保跟踪两个赤字。 该算法恰好执行了三个直接匹配并达到了目标分布。
