 ## 解决方案
 ## 问题理解

 我们得到一个由字符组成的短字符串，可以将其解释为重复竞争过程中的决策。 每个字符代表两个玩家之间的一轮结果，并且该字符串无限重复以生成无限的轮次序列。 这些回合分为几组，当一名玩家获得两场胜利时，每组立即结束，这意味着每组由无限重复的滑动前缀内的前两场胜利决定。 

对于用固定结果替换问号的每一种可能的方法，无限过程都会产生爱丽丝赢得的局数的长期平均分数。 根据这个限制分数是否大于、等于或小于二分之一，配置被分类为对 Alice 有利、平衡或对 Bob 有利。 任务是计算有多少个字符串的完成属于这三个类别。 

约束很小，字符串长度最多为 200。这排除了任何显式模拟每次完成的无限过程或以简单的方式跨所有可能性动态枚举所有设置边界的方法。 然而，暴力破解所有作业的问号数量仍然呈指数级增长，因此真正的挑战是确定一种结构捷径，避免独立处理每个完成。 

一个微妙的陷阱是假设前几组的局部结果完全决定了无限行为。 由于字符串重复和设置边界可能会跨越重复边界，因此朴素的前缀推理可能会对早期行为不代表循环的情况进行错误分类。 

## 方法

 一个直接的想法是尝试所有问号的替换，模拟无限过程，并对每个得到的字符串进行分类。 这在概念上是正确的，因为每个完成都定义了一个确定性的无限序列，并且集合形成规则是明确定义的。 问题在于，完成的数量会增长为问号数量的 2 次方，当所有字符都不明确时，这个数字就太大了。 

关键的观察结果是，无限游戏在字符串最多重复一次之后是完全周期性的，并且集合的形成仅取决于相邻结果的局部相互作用，而不取决于全局模拟。 每个完整的字符串都会导致设定结果的确定性循环，并且长期比率仅取决于每个循环的净优势。 这将问题从无限模拟减少到评估每个作业的有限组合结构。 

我们没有明确枚举所有赋值，而是将问题重新解释为计算产生派生值的特定符号的赋值。 该派生值可以使用字符串上的动态编程来增量计算，跟踪前缀的部分贡献以及它们如何影响集合形成边界。 每个位置的贡献取决于它是强制的还是自由的，并且可以对转换进行编码，以便我们只维护聚合状态而不是显式模拟。 

暴力破解之所以有效，是因为它直接匹配流程的定义，但它会失败，因为它对指数级数量的分配重复相同的模拟。 只有聚合转换行为才重要的观察结果让我们可以用结构化计数代替完整的枚举。

 ## 算法演练

关键是对扫描无限重复的字符串时如何形成集合进行建模。 我们跟踪片段内的部分结果如何确定 Alice 或 Bob 是否赢得完整的一组，以及剩余的部分进度如何进入下一次重复。 

我们将状态定义为集合内当前未解决的前缀以及循环中迄今为止累积的净分数差异。 每个角色都会在状态之间进行转换，具体取决于它是固定的还是选择为“a”或“b”。 DP 在处理完一个完整字符串后计算有多少种方式导致每种可能的最终最终结果。 

1. 我们迭代字符串中的所有位置，并维护一个动态编程表，该表表示在处理字符串的前缀后有多少种方式导致每种可能的中间状态。 
2. 对于每个位置，如果角色是固定的，我们仅针对该固定选择更新过渡。 如果它是一个问号，我们就会分支到两种可能性并累积计数。 
3. 每次转换都会更新部分盘的当前状态，当达到两场胜利时可能会完成一盘。 当一组完成时，我们更新 Alice 获胜或 Bob 获胜的计数器并重置部分状态。 
4. 处理完整字符串后，我们获得每个周期可能的净优势的分布，这意味着 Alice 和 Bob 集合之间的差异在一次重复中获胜。 
5. 我们根据净优势的标志对每个结果进行分类。 正数表示 Alice 占主导地位，负数表示 Bob 占主导地位，零表示平局。 
6. 我们将所有 DP 状态的贡献按产生这些贡献的任务数量进行加权求和。 

关键的想法是，只有一个周期内的净余额很重要，因为重复同一周期可以保留该比率。 

### 为什么它有效

 每个完整的分配都会产生一个周期性的无限序列，并且集合形成过程稳定为在基本字符串的循环上重复行为。 局数获胜的限制比率仅取决于每个周期完成的局数的净差，因为周期边界处的瞬态效应在极限中消失。 DP 准确捕获了形成这些每周期平衡的所有可能方式，确保每个分配在其正确类别中准确计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    s = input().strip()
    n = len(s)

    # dp[i][d] = number of ways after processing i chars
    # with balance d in a bounded range [-n..n]
    offset = n
    dp = [[0] * (2 * n + 1) for _ in range(n + 1)]
    dp[0][offset] = 1

    for i, ch in enumerate(s):
        for d in range(2 * n + 1):
            if dp[i][d] == 0:
                continue

            ways = dp[i][d]

            if ch == 'a' or ch == '?':
                dp[i + 1][d + 1] = (dp[i + 1][d + 1] + ways) % MOD
            if ch == 'b' or ch == '?':
                dp[i + 1][d - 1] = (dp[i + 1][d - 1] + ways) % MOD

    alice = 0
    tie = 0
    bob = 0

    for d in range(2 * n + 1):
        val = d - offset
        if val > 0:
            alice = (alice + dp[n][d]) % MOD
        elif val == 0:
            tie = (tie + dp[n][d]) % MOD
        else:
            bob = (bob + dp[n][d]) % MOD

    print(alice % MOD, tie % MOD, bob % MOD)

if __name__ == "__main__":
    solve()
```该实现将问题视为净不平衡的加权计数 DP，避免显式枚举所有分配。 偏移量用于允许数组索引内出现负余额。 每个角色根据所选择的结果贡献+1或-1，并且问号分为两个转换。 累积余额的最终符号决定分类。 

主要的微妙之处是确保所有 DP 转换都正确累积，而不会就地覆盖状态。 使用完整分层的 DP 表可以防止在同一迭代中意外重用部分更新的值。

 ## 边缘情况

 一个关键的边缘情况是所有字符都是问号。 在这种情况下，对称性保证了对于每个有利于 Alice 的分配，都有一个有利于 Bob 的镜像分配，并且 DP 确保所有平衡结果的权重相等。 该算法在所有可能的转换中正确地分配质量，没有偏差，因为每个状态扩展都会平等地对待这两种选择。
