 ## 解决方案
 ## 问题理解

 我们正在处理一个未知正整数数组，其中每对不同的元素都是互质的。 我们与该数组交互的唯一方法是通过返回两个位置的乘积的查询。 每个查询选择两个索引并返回相应隐藏值的乘积。 

任务是重建整个数组，同时最小化此类产品查询的数量。 对数组大小的限制足够小，以至于我们可以采用精心构造的重建策略，但又足够大，以至于在严格的查询预算模型中，幼稚的每个元素隔离仍然处于边界。 

关键的结构前景非常强大：任何两个不同的元素都没有共同的素因数。 这意味着，每当一个产品涉及两个不同的元素时，如果两个查询的产品在一个索引处重叠，则不同产品之间唯一共享的信息来自单个公共元素。 

一种简单的方法是尝试通过将每个元素与固定的参考元素相结合来独立地确定每个元素。 例如，固定索引 1 并查询每对 (1, i) 会得到直接乘积 a1 * ai，如果 a1 已知，则其他一切都会立即发生。 但 a1 是未知的，单独恢复它会花费额外的整轮查询，使得总查询数大约为 2N。 

不明显的边缘情况是当我们尝试按顺序恢复元素而不确保重叠结构时。 如果我们查询像 (1,2)、(3,4)、(5,6) 这样的不相交对，我们就得不到共享的因子结构，并且 gcd 关系变得毫无用处。 例如，对于值 [2,3,5,7]，乘积 (2·3)=6 和 (5·7)=35 不共享索引，因此 gcd(6,35)=1 不给出可恢复元素。 正确的输出仍然是原始数组，但这样的查询策略破坏了所有可重构性。 

因此，问题不仅在于高效查询，还在于设计允许 gcd 提取单个隐藏值的重叠。 

## 方法

 直接的强力方法是将每个元素视为未知元素，并尝试对每个位置使用多个查询来隔离它。 人们可以尝试通过查询 (i, j) 中的多个 j 值并使用 gcd 求解方程组来恢复每个 ai。 然而，任何此类方法都会很快退化为 O(N^2) 查询，因为每个元素都需要足够的独立方程来消除未知的邻居。 

关键的见解来自于利用产品在重叠时如何共享一个隐藏变量。 如果我们采用两个共享索引 j 的乘积，例如 ai * aj 和 aj * ak，它们的 gcd 为：

 gcd(ai * aj, aj * ak) = aj * gcd(ai, ak)

 由于所有不同元素都是成对互质的，因此 gcd(ai, ak) = 1，因此 gcd 恰好变为 aj。 这将共享索引变成了我们可以直接提取的东西。 

这意味着如果我们将元素分组为重叠的三元组，我们只需使用两个查询即可恢复每个三元组的中间元素。 每对相邻产品共享中间索引，使我们能够剥离出隐藏的值。 

我们现在不再是每两个查询隔离一个元素，而是每两个查询隔离一个元素，同时前进三个位置。 这将效率从大约 2N 查询提高到大约 2N/3。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N^2) 查询 | O(1) | O(1) | 太慢了|
 | 三重重叠结构| O(N) 查询 | O(N) | 已接受 |

 ## 算法演练

 我们通过在三个连续索引的重叠组中处理数组来构造数组。

1.修复三个索引i、i+1、i+2的滑动窗口。 目标是恢复中间元素ai+1。 
2. 查询窗口中前两个元素的乘积，得到x = ai * ai+1。 
3. 查询窗口中最后两个元素的乘积，得到 y = ai+1 * ai+2。 
4. 计算 gcd(x, y)。 因为两个乘积都包含 ai+1，所以 gcd 精确地分离了 ai+1，因为 ai 和 ai+2 是互质的。 这产生 ai+1。 
5. 存储恢复的中间元素并将窗口向前移动三个位置，重复该过程。 
6. 处理完整的三元组后，处理最后剩余的索引。 由于构建是基于三人一组，因此最多保留两个元素。 这些可以通过与已知的相邻元素配对或通过最终的直接查询（如果需要）来恢复。 

它起作用的原因与一个不变量有关：每个恢复的 gcd 来自两个产品，它们恰好共享一个公共索引，并且所有其他索引对都是互质的。 这确保了 gcd 操作中不会存在任何无关因素。 每一步都干净地隔离一个未知元素，而不会受到邻居的污染，并且后续操作不会依赖于未恢复的值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(i, j):
    print("?", i, j)
    sys.stdout.flush()
    return int(input())

def solve():
    n = int(input())
    a = [0] * (n + 1)

    i = 1
    while i + 2 <= n:
        x = ask(i, i + 1)
        y = ask(i + 1, i + 2)
        a[i + 1] = gcd(x, y)
        i += 3

    # remaining tail handling
    if n % 3 == 1:
        if n >= 2:
            a[n] = ask(n - 1, n) // a[n - 1]
    elif n % 3 == 2:
        a[n - 1] = ask(n - 1, n) // a[n]

    print("!", *a[1:])

def gcd(x, y):
    while y:
        x, y = y, x % y
    return x

if __name__ == "__main__":
    solve()
```该解决方案围绕交互式查询帮助程序构建，该帮助程序打印查询并立即读取响应。 gcd函数是手动实现的，以避免依赖。 

主循环以三个索引为步长进行。 每次迭代恰好执行两个查询并恢复三元组的中间元素。 关键点是我们从不尝试同时恢复三元组的两个端点，因为这会丢失 gcd 提取所需的重叠结构。 

尾部处理取决于完整三元组后剩余的元素数量。 由于最多只剩下两个索引，一旦推断出其中一个索引，就可以通过将已知乘积除以已知邻居来恢复它们。 

正确性取决于确保每次除法都是精确的，这是从互质条件得出的。 

## 工作示例

 考虑一个数组 [2, 3, 5, 7, 11, 13]。 

我们以三元组的形式处理索引。 

| 步骤| 查询 x | 查询 y | 最大公约数（x，y）| 已知值|
 | ---| ---| ---| ---| ---|
 | (1,2,3) | (1,2,3) | 2·3=6 | 3·5=15 | 3·5=15 3 | a2=3 | a2=3 |
 | (4,5,6) | 7·11=77 | 7·11=77 11·13=143 | 11 | 11 a5=11 | a5=11 |

 处理后，我们通过已知产品的除法直接计算剩余值。 

该迹线表明每个中间元素都是独立提取的，没有干扰，证实没有发生交叉三重污染。 

现在考虑一个较小的例子 [6,35,77]。 尽管值不是质数，但它们在各个位置上仍然是成对互质的。 

| 步骤| 查询 x | 查询 y | 最大公约数（x，y）| 已知值|
 | ---| ---| ---| ---| ---|
 | (1,2,3) | (1,2,3) | 6·35=210 | 35·77=2695 | 35 | 35 a2=35 | a2=35 |

 即使值是复合的，只要不同索引之间的互质性成立，gcd 也会隔离中间元素。 

这证明了对价值大小和构成的稳健性。

 ## 边缘情况

 关键的边缘情况是 N 不能被 3 整除。假设 N=4，值为 [a1, a2, a3, a4]。 该算法处理(1,2,3)并恢复a2。 然后我们留下索引 4，但也留下了通过早期查询间接获得的关于索引 3 的部分信息。 最终的恢复必须避免假设剩余元素的两个邻居都是已知的； 否则将尝试使用未初始化的值进行除法。 

另一个边缘情况是 N=1。 无需查询，直接输出单个元素。 任何应用三重策略的尝试都会错误地访问越界索引。 

最后一个微妙的情况是值很大并且是复合的，例如 [30, 49, 77]。 尽管值共享许多内部因素，但索引之间的成对互质性确保了 gcd 行为仍然隔离共享的中间元素。 该算法保持稳定，因为它从不依赖于素性，仅依赖于跨索引互质性。
