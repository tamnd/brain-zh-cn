[CF 1736B - 玩转 GCD](https://codeforces.com/problemset/problem/1736/B)

 **求解时间：** 4m 30s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们得到一个数组`a`。 我们想知道是否存在另一个数组`b`长度`n + 1`使得每个元素`a`是两个相邻元素的 GCD`b`:

 [
 a_i = \gcd(b_i, b_{i+1})
 ]

 对于每个职位。 

任务不是通过反复试验来构建任意有效的序列。 我们只需要确定是否至少存在一个这样的序列。 

所有测试用例中所有数组的总长度最多为 (10^5)。 这立即排除了对 (b) 的可能值的任何搜索。 即使是二次算法也会有风险。 每个测试用例我们需要一个线性或近线性的解决方案。 

一个微妙的点是相邻的 GCD 要求是相互作用的。 满意

 [
 \gcd(b_i,b_{i+1})=a_i
 ]

 和

 [
 \gcd(b_{i+1},b_{i+2})=a_{i+1}
 ]

 同时对共享值(b_{i+1})施加限制。 局部选择可以轻松打破邻近约束。 

考虑：

 [
 a=[4,2,4]
 ]

 答案是`NO`。 幼稚的方法可能会注意到每个相邻的对看起来兼容并错误地接受。 中间的 GCD 迫使共享值包含使相邻 GCD 之一大于所需值的因素。 

另一个重要的边缘情况是 (n=1)。 任何正整数都可以实现为两个相等数的 GCD，因此答案始终是`YES`。 

例如：

 [
 一个=[343]
 ]

 选择 (b=[343,343])。 

## 方法

 蛮力策略会尝试直接构建 (b) 的值。 由于（b）的条目没有以任何有用的方式限制，因此搜索空间是巨大的。 即使将候选限制为附近值的约数也不会产生实用的算法。 

关键的观察是存在一个规范的候选序列。 

假设我们已经知道所有 GCD 值。 必须同时参与的号码

 [
 a_i=\gcd(b_i,b_{i+1})
 ]

 和

 [
 a_{i+1}=\gcd(b_{i+1},b_{i+2})
 ]

 应包含两个相邻约束所需的所有素因子。 最小的这样的选择是

 [
 \运算符名称{lcm}(a_i,a_{i+1})。 
]

 这表明构建

 [
 b_1=a_1,
 ]

 [
 b_{n+1}=a_n,
 ]

 以及内部职位

 [
 b_i=\运算符名{lcm}(a_{i-1},a_i)。 
]

 如果存在任何有效序列，则该结构是最强的候选结构。 然后我们简单地验证它是否确实重现了所有必需的 GCD。 

对于每个位置 (i)，计算

 [
 \gcd(b_i,b_{i+1})。 
]

 如果它到处都等于 (a_i)，则答案是`YES`。 否则就是`NO`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | LCM构建+验证| (O(n \log V)) | (O(n)) | (O(n)) | 已接受 |

 这里（V）是最大数组值。 

## 算法演练

 1. 读取数组(a)。 
2. 如果(n=1)，回答`YES`。 
3. 构造辅助数组(b)。 

套装

 [
 b_1=a_1,
 \qquad
 b_{n+1}=a_n。 
]
 4. 对于每个内部位置 (2 \le i \le n)，设置

 [
 b_i=\运算符名{lcm}(a_{i-1},a_i)。 
]

 这是可同时被两个相邻 GCD 要求整除的最小值。 
5. 对于每个 (i)，计算

 [
 g_i=\gcd(b_i,b_{i+1})。 
]
 6. 如果有(g_i \ne a_i)，请回答`NO`。 
7. 否则回答`YES`。 

### 为什么它有效

 (b) 的每个内部元素都必须能被两个相邻的 GCD 值整除。 最小公倍数是具有该性质的最小数。 

如果 LCM 构造已经产生比某个位置所需的更大的 GCD，则每个其他有效候选者将至少包含相同的素因数，并且无法将该 GCD 降低回所需值。 因此，这种构造的失败证明是不可能的。 

相反，如果所有计算出的 GCD 都与目标数组匹配，则构造的序列本身就是有效的见证。 因此，测试既是必要的，也是充分的。 

## Python 解决方案```python
import sys
from math import gcd

input = sys.stdin.readline

def lcm(a, b):
    return a // gcd(a, b) * b

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    b = [0] * (n + 1)
    b[0] = a[0]
    b[n] = a[-1]

    for i in range(1, n):
        b[i] = lcm(a[i - 1], a[i])

    ok = True

    for i in range(n):
        if gcd(b[i], b[i + 1]) != a[i]:
            ok = False
            break

    print("YES" if ok else "NO")
```构建阶段用 LCM 值填充内部位置。 验证阶段对每个所需的 GCD 只检查一次。 

最小公倍数公式

 [
 \operatorname{lcm}(x,y)=\frac{x}{\gcd(x,y)}y
 ]

 避免具有固定大小整数的语言中的溢出问题。 Python 自动处理大整数，但标准做法是相同的公式。 

索引是唯一经常出现相差一错误的地方。 辅助数组的长度为 (n+1)，而原始数组的长度为 (n)。 

## 工作示例

 ### 示例 1

 [
 a=[4,2]
 ]

 构造：

 | 职位| 价值|
 | --- | --- |
 | (b_1) | 4 |
 | (b_2) | lcm(4,2)=4 |
 | (b_3) | 2 |

 验证：

 | 检查 | 价值|
 | --- | --- |
 | 最大CD(4,4) | 4 |
 | 最大公约数(4,2) | 2 |

 两者都与目标数组匹配。 

回答：`YES`。 

### 示例 2

 [
 a=[4,2,4]
 ]

 构造：

 | 职位| 价值|
 | --- | --- |
 | (b_1) | 4 |
 | (b_2) | 4 |
 | (b_3) | 4 |
 | (b_4) | 4 |

 验证：

 | 检查 | 价值|
 | --- | --- |
 | 最大CD(4,4) | 4 |
 | 最大CD(4,4) | 4 |
 | 最大CD(4,4) | 4 |

 中间的值应该是2，但变成了4。 

答：`NO`。 

这个例子说明了为什么本地兼容性不够。 共享元素迫使中间 GCD 大于要求的值。

 ## 边缘情况

 对于 (n=1)，算法构造 (b=[a_1,a_1])。 验证步骤恰好计算出一个 GCD，它等于 (a_1)。 答案总是`YES`。 

对于相邻值相除的数组，例如

 [
 [8,4,2],
 ]

 LCM 结构给出

 [
 [8,8,4,2]。 
]

 每个验证 GCD 都与目标序列匹配，因此算法正确接受。 

对于数组，例如

 [
 [4,2,4],
 ]

 该结构产生一个中间值，该值被迫包含两侧的因子 (2^2)。 验证发现生成的 GCD 是 (4) 而不是 (2)，证明不存在有效序列。
