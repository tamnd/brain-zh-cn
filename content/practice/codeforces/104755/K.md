 ## 解决方案
 ## 问题理解

 我们得到了一个部分填充的 4 x 4 网格，必须将其完成为有效的“四数独”变体。 每个单元格包含 1 到 4 之间的数字，但某些单元格为零并且必须填写。 

规则简单但严格。 每行必须仅包含数字 1、2、3、4 一次。 每列还必须包含每个数字恰好一次。 最后，四个 2 x 2 子方格中的每一个也必须包含所有四个数字恰好一次。 

该实例的特殊结构是左上角的2×2块和右下角的2×2块已经完全填充并且有效。 右上角和左下角的块是空的，这意味着它们的所有单元格都为零。 任务是判断网格是否可以补全为有效解，如果可以，则输出补全的网格。 

网格大小固定为 4 × 4，因此不排除约束条件下的暴力破解。 唯一真正的挑战是避免在同时处理行、列和块约束时出现推理错误。 

最危险的边缘情况是本地行完成似乎可行但违反了列约束或 2 × 2 块约束。 例如，如果某列的左上角块中已包含 1，则在同一列的左下角块中放置另一个 1 会立即破坏有效性，即使行看起来仍然正确。 

由于网格非常小并且填充区域是结构化的，因此忽略约束传播的简单方法仍将快速终止，但如果在每次分配时不仔细遵守所有三个约束，则很容易放错数字。 

## 方法

 一种直接的方法是将其视为约束满足问题。 我们总共有 8 个空单元格，全部位于右上角和左下角的 2 x 2 块中。 每个单元格都可以采用四个值之一。 暴力策略会尝试对这些空单元格进行所有分配，最多给出 4^8 种可能性。 

对于每个完整的分配，我们将检查所有行、列和子网格约束。 这是正确的，因为它枚举了所有可能性，但配置数量为 65536，并且每次验证都需要多次扫描网格。 这仍然足够小，但这是不必要的工作。 

关键的观察结果是，由于固定的 4 x 4 大小以及已经完成的对角块的存在，数独约束的结构非常严格。 每行恰好与一个填充的 2 x 2 块和一个空的 2 x 2 块相交。 这意味着一旦一行被部分填充，缺失的两个值将通过从集合 {1,2,3,4} 中消除来强制执行。 这同样适用于列。 

我们可以使用约束传播逐步填充空单元格，而不是随意猜测。 在任何时候，如果一行恰好有两个缺失单元格，则它们的值由该行中尚未使用的剩余数字确定。 一旦放置了一个值，它会立即约束其列和块，从而级联进一步的强制放置。 

由于网格非常小，并且初始填充的块已经是完整的排列，因此这种传播无需深度回溯即可收敛。 如果在任何时候出现矛盾，例如空单元格没有有效数字，我们就得出不可能的结论。

 ## 算法演练

 我们将网格视为在约束消除下不断发展，直到不可能取得进展为止。

1. 从给定的 4 x 4 网格开始，记录每行、列和 2 x 2 块中已经出现的数字。 这种簿记是至关重要的，因为每个决定都是由缺失的东西驱动的，而不是现有的。 
2. 重复扫描所有空单元格。 对于每个单元格，计算其行、列和块中尚未使用的从 1 到 4 的数字集。 如果恰好有一位数字可能，请立即分配它。 这是强制移动，因为任何其他值都会立即违反约束。 
3. 为单元格赋值后，更新行、列和块记录。 这可能会减少其他单元中的可能性，因此该过程必须迭代地继续，直到没有新的强制分配出现。 
4. 如果在扫描过程中我们发现一个单元格的有效候选数为零，则我们终止并返回“否”，因为没有完成可以满足所有约束。 
5. 如果所有单元格都被填满，则输出完整的网格。 

其有效运作的原因是每个放置同时减少多个方向的熵。 在 4 x 4 拉丁方结构中，每个数字在每行和每列中恰好出现一次，因此放置一个数字可以有效地将其从三个约束域中一次性删除。 

### 为什么它有效

 该算法在每一步都保持一致的部分拉丁方。 不变量是所有填充的单元格满足行、列和块唯一性约束，并且所有未填充的单元格表示至少保留一位有效数字的位置。 

每个分配都是通过消除由三个独立集（行、列、块）约束的大小为 4 的域来强制进行的。 由于网格非常小，任何有效的解决方案最终都必须暴露强制移动，直到完成。 如果在某个时刻不存在强制移动，则剩余的歧义将需要分支，但初始条件确保解决方案（如果存在）的唯一性，从而防止歧义持续存在。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def block_id(r, c):
    return (r // 2) * 2 + (c // 2)

def solve():
    g = [list(map(int, input().split())) for _ in range(4)]

    row = [set() for _ in range(4)]
    col = [set() for _ in range(4)]
    blk = [set() for _ in range(4)]

    empty = []

    for r in range(4):
        for c in range(4):
            v = g[r][c]
            if v == 0:
                empty.append((r, c))
            else:
                row[r].add(v)
                col[c].add(v)
                blk[block_id(r, c)].add(v)

    changed = True
    while changed:
        changed = False
        new_empty = []
        for r, c in empty:
            if g[r][c] != 0:
                continue
            b = block_id(r, c)
            candidates = []
            for v in range(1, 5):
                if v not in row[r] and v not in col[c] and v not in blk[b]:
                    candidates.append(v)

            if len(candidates) == 0:
                print("No")
                return
            if len(candidates) == 1:
                v = candidates[0]
                g[r][c] = v
                row[r].add(v)
                col[c].add(v)
                blk[b].add(v)
                changed = True
            else:
                new_empty.append((r, c))
        empty = new_empty

    for r in range(4):
        for c in range(4):
            if g[r][c] == 0:
                print("No")
                return

    print("Yes")
    for row_vals in g:
        print(*row_vals)

if __name__ == "__main__":
    solve()
```该实现使用三个集合数组来跟踪约束，一个用于行，一个用于列，一个用于 2 x 2 块。 功能`block_id`对块结构进行编码，以便每个单元都映射到四个块之一。 

主循环重复扫描所有未解析的单元格并计算有效的候选单元格。 关键的实现细节是，我们仅在该值是唯一有效选项时才提交该值。 这样可以避免推测性猜测并确保正确性而无需回溯。 

一个微妙的点是更新`empty`每次通过后列出。 这可以防止重复地重新考虑已经解析的单元并保持循环的高效和有限。

 ### 示例 1

 输入：```
1 2 0 0
3 4 0 0
0 0 4 3
0 0 1 2
```初始状态：

 | 步骤| (0,2) | (0,3) | (1,2) | (1,3) | 进展|
 | --- | --- | --- | --- | --- | --- |
 | 初始化| {3,4} | {3,4} | {1,2} | {1,2} | 0 已满 |

 第一遍分配 (0,2)=3, (0,3)=4，因为第 0 行恰好缺少这些数字。 同样，第 1 行强制其缺失值。 传播后，列约束强制将剩余位置放置在左下块中。 

最终的网格完全确定，没有矛盾。 

该跟踪表明，仅行约束就已经足够强大以开始传播，而列/块约束只能细化该过程。

 ## 边缘情况

 当除一个单元格之外的一行已完全确定，但该单元格违反列约束时，就会出现一种边缘情况。 例如，如果一行是`[1, 2, 0, 4]`和列约束禁止`3`在最后一个位置，算法正确地识别出唯一的候选集为空并立即输出“No”。 

另一种情况是，传播导致即使存在解，也无法唯一确定单元格的情况。 在这个问题中，这种情况不会出现，因为初始对角线块固定了足够的结构来强制确定性级联，因此缺乏进展意味着在给定的约束下不可能。 

最后一种情况是在出现任何强制移动之前需要多次通过。 循环结构确保了这一点得到处理，因为我们在每次更新后都会重新计算候选者，直到稳定为止。
