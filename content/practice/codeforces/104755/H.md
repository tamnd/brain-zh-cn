 ## 解决方案
 ## 问题理解

 我们得到了平面上的一组直线。 每条线都保证是三个特殊方向之一： 表格的水平线$y = c$，表格的垂直线$x = c$，以及表格的对角线$x + y = c$。 所有常数$c$是整数并且所有行都是不同的。 

任务是计算可以形成多少个非退化三角形，使得三角形的每条边完全位于给定的直线上。 有效的三角形是通过选择三条线来确定的，这三条线的两两相交形成三个不同的点，以便这些点形成一个正确的三角形，而不是所有三条线在一个点相交或其中两条线平行的简并配置。 

关键的结构约束是边缘被限制为恰好位于所提供的线上，这意味着每个三角形对应于选择三条线，每条线对应一条边，并要求这三条线在三个不同的点处成对相交。 

界限$n \le 3000$立即排除任何$O(n^3)$三元组的枚举。 甚至$O(n^2)$是临界值，但如果每对都在恒定时间内处理，则可行。 线族的结构强烈表明我们应该避免推理任意交叉点，而应利用仅存在三个方向的事实。 

一个微妙的问题是并发引起的退化。 三条线可能会在一个点相交，例如当水平线、垂直线和对角线共享一个公共交点时就会发生这种情况。 另一个失败的情况是选择两条相同方向的线，它们是平行的并且不能形成三角形边对。 

例如，如果我们采取$y = 0$,$x = 0$， 和$x + y = 0$，所有三条线都在原点相交，因此尽管我们有三条有效线，但它们并不形成三角形。 仅检查成对交集而不强制执行不同顶点的简单计数方法会过度计算此类配置。 

## 方法

 直接的强力解决方案将迭代所有三条线并测试它们是否形成有效的三角形。 对于每个三元组，我们将计算三个成对的交点并检查它们是否全部不同。 这在概念上是简单且正确的，因为任何三角形都必须由三条线组成。 

然而，三元组的数量是$\binom{n}{3}$，这大约是$4.5 \times 10^9$什么时候$n = 3000$。 即使采用极快的交集计算，这也远远超出了 0.25 秒允许的范围。 

关键的观察结果是几何形状是高度结构化的。 只存在三个方向，因此任何三角形都必须恰好由一条水平线、一条垂直线和一条对角线组成。 任何其他组合都是不可能的：两条平行线不能相交，因此两条水平线、两条垂直线或两条对角线不能形成闭合三角形边界。 

一旦我们将自己限制为每种类型的一条线，交点就完全确定了。 一条水平线$y = h$，一条垂直线$x = v$，和一条对角线$x + y = d$两两相交于：$(v, h)$,$(d - h, h)$， 和$(v, d - v)$。 这三个点形成一个三角形，除非所有三条线都交于同一点，这恰好发生在$h + v = d$。 这种情况会使所有交叉点塌陷到一个点，从而产生一个退化三角形。 

因此问题就简化为计算三元组$(H, V, D)$这样$h + v \ne d$。 

我们可以计算一条水平线、一条垂直线和一条对角线的所有三元组，然后减去其中的退化情况$h + v = d$。 第一部分很简单$|H| \cdot |V| \cdot |D|$。 第二部分可以通过迭代对来计算$(h, v)$并检查对角线是否具有值$h + v$存在。 

这将问题转化为对 3000 以内的值进行频率计数的任务。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解三倍以上 |$O(n^3)$|$O(1)$| 太慢了|
 | 按类型+散列计数 |$O(n^2)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将输入线分为三组：水平线、垂直线和对角线。 我们还维护对角常数的频率数组或哈希集，以便我们可以在常数时间内测试成员资格。 

1.读取所有行并将水平常量存储在列表中$H$, 列表中的垂直常量$V$，并标记布尔数组或集合中的对角常量$D$。 此预处理允许稍后快速进行存在性检查。 
2. 计算从每个族中选取一行所形成的三元组的总数。 这是$|H| \cdot |V| \cdot |D|$。 在考虑简并性之前，每个这样的三元组都是候选三角形。 
3. 迭代所有对$(h, v)$在哪里$h \in H$和$v \in V$。 对于每对计算$s = h + v$。 如果$s$存在于对角集中，则三元组$(h, v, s)$是退化的，必须被排除。 
4. 从之前计算的总乘积中减去此类简并三元组的数量。 每个有效$(h, v)$恰好贡献了一条禁止对角线，因此不会发生过度计数。 
5. 输出最终校正后的计数。 

关键思想是简并性不是需要完全交集计算的几何性质，它纯粹是连接三个线参数的代数相等条件。 

### 为什么它有效

 每个有效的三角形必须在每个方向上恰好使用一条线，因为平行线不能形成三角形边。 给定一个固定的水平$y = h$和垂直的$x = v$，交点被迫为$(v, h)$，并且对角线必须经过该点才能使三角形塌陷。 当且仅当$h + v = d$。 每对这样的对都精确地标识了一个对角常数，因此减去这些情况会删除所有且仅删除简并配置。 不存在其他简并性，因为任何不匹配的三元组都会产生三个不同的成对交集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    H = []
    V = []
    D = [0] * 6005  # since c up to 3000, sums up to 6000

    hasD = set()

    for _ in range(n):
        d, c = input().split()
        c = int(c)
        if d == 'H':
            H.append(c)
        elif d == 'V':
            V.append(c)
        else:
            hasD.add(c)

    total = len(H) * len(V) * len(hasD)

    bad = 0
    for h in H:
        for v in V:
            if (h + v) in hasD:
                bad += 1

    print(total - bad)

if __name__ == "__main__":
    main()
```该实现是计数思想的直接翻译。 分成三个列表可确保我们永远不会混合不兼容的方向。 当测试三元组是否退化时，对角线集允许常量时间隶属度检查。 

一个微妙的点是，每个$(h, v)$对正好对应一个对角线值$h+v$，所以计算不良情况是线性的$|H| \cdot |V|$无需搜索对角线。

 ## 边缘情况

 关键的边缘情况是每对水平线和垂直线都与对角线匹配。 例如，如果$H = \{0,1\}$,$V = \{0,1\}$，对角线包括所有总和$\{0,1,2\}$，那么每一对都会产生一个简并构型。 该算法通过为每对减去一个，删除所有三角形来处理这个问题。 

另一种情况是不存在对角线时。 然后设置检查总是失败，所以不会发生减法，答案很简单$|H| \cdot |V| \cdot 0 = 0$，这正确地反映了没有三个方向就无法形成三角形。 

最后的极端情况是存在少于三个方向的最小输入。 乘积项已经变为零，因此算法自然返回零，无需任何特殊处理。
