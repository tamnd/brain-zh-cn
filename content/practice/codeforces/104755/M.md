 ## 问题理解

 我们正在研究一个无限六边形网格，其中每个单元有六个邻居，距离以六边形之间边到边移动的最小数量来测量。 蚱蜢从原点开始，执行无限序列的跳跃。 在时间步$i$，它必须精确移动$i$单元格在六个网格方向之一的直线上。 

该运动还有两个额外的限制。 每次跳跃后，就六角距离而言，蚱蜢必须比该跳跃之前严格远离原点。 此外，如果在相同规则下可以使用更少的跳跃到达该单元格，则不允许蚱蜢降落在该单元格上，这意味着每个访问的位置在到达它所用的跳跃次数方面必须是最佳的。 

对于每个查询单元格$(x, y)$，我们必须决定是否存在某种跳跃方向序列，以便蚱蜢最终降落在该单元格上，同时尊重这两个约束。 

的限制$t \le 10^5$和坐标高达$10^9$意味着每个查询必须在常数或对数时间内得到回答。 任何一步步模拟跳转的方法都是立即不可能的，因为即使是单个查询也可能需要多达$\sqrt{10^9}$如果我们根据距离进行推理，则需要更多步骤。 

一个天真的陷阱是认为我们可以贪婪地模拟从原点向外的跳跃。 例如，尝试模拟：$$0 \to 1 \to 3 \to 6 \to 10 \to \dots$$在实际的网格位置中失败是因为每一步都有方向选择并且状态空间呈指数增长。 另一个微妙的问题是假设坐标的单调性。 即使距离增加，由于六角几何形状，坐标也会在一个轴上减少，因此任何坐标推理都会很快中断。 

第二个错误的想法是将其视为具有加权步骤的最短路径问题，但权重取决于时间，因此标准 BFS 或 Dijkstra 不适用。 

## 方法

 暴力解释就是模拟每次选择方向的过程$i$，在每个步骤后跟踪所有可到达的单元格，同时强制执行约束。 步骤后$k$，我们将维护一组随着距离限制的增加而可到达的所有可能位置。 

在步骤$i$，每个状态分支成六个可能的方向，因此状态数量的增长大致如下$6^i$。 即使使用距离约束进行剪枝，之后的可达状态数$k$步数仍然是指数级的$k$。 由于坐标可以大到$10^9$，到达远处单元格所需的步数约为$\sqrt{10^9}$，使得这完全不可行。 

关键的观察结果是，关于细胞唯一重要的是它与原点的六角距离，而不是它的确切位置。 每次跳跃都会增加一定量的距离，该量由方向选择控制，但之后的总效果$k$跳跃受到步长总和的限制：$$S_k = 1 + 2 + \dots + k = \frac{k(k+1)}{2}.$$因为每次移动都要严格增加到原点的距离，之后的距离$k$步骤单调。 这迫使最终的可达距离$d$位于一个非常紧密的信封内$S_k$。 灵活性来自于方向选择：在每一步中，部分运动可以有效地“取消”六边形几何中其他方向的进展，这使得最终距离不同于$S_k$同时仍然保持严格的单调增长。 

这减少了检查目标六角距离是否正确的问题$d$可以通过一定数量的步骤来匹配$k$， 在哪里$k$必须足够大$S_k \ge d$，以及剩余的松弛$S_k - d$可以通过选择减少净向外进展而不违反单调性的方向来“吸收”。 在这个结构中，唯一剩下的障碍是奇偶校验：在基础晶格对称性中，松弛必须以 2 为单位进行分配。 

因此我们将每个查询减少为计算十六进制距离$d$，找到最小的$k$这样$S_k \ge d$，并检查是否$S_k - d$是均匀的。

 ## 算法演练

 我们使用其标准坐标系来处理六角网格，其中可以在恒定时间内计算到原点的距离。 

### 1. 将坐标转换为十六进制距离

 我们计算：$$d = \text{hex\_distance}(x, y)$$这给出了在没有跳跃约束的情况下到达正常六角网格中的单元格所需的最少步数。 

确切的公式取决于轴坐标系，但它总是可以表示为从立方坐标导出的最大线性形式。 

### 2. 找到无约束累积模型中所需的最小跳跃次数

 我们想要最小的$k$这样：$$S_k = \frac{k(k+1)}{2} \ge d$$我们使用直接二次解或通过递增来计算$k$直到不等式成立。 自从$k$最多是关于$5 \cdot 10^4$为了$d \le 10^9$，这仍然很快。 

### 3.检查可行性条件

 曾经$k$是固定的，我们计算：$$\text{slack} = S_k - d$$当且仅当满足以下条件时，我们才会接受该单元格：$$\text{slack} \bmod 2 = 0$$奇偶条件确保剩余的多余运动可以在六角方向上对称地重新分配，而不会违反严格的距离增加规则。 

### 为什么它有效

 该过程有效地将可达距离限制为可表示为步长的近三角形和的距离。 单调距离要求迫使我们“用尽”足够的总步长来至少达到$d$，并且任何剩余都必须通过反转六角晶格中成对方向的进度来抵消。 由于这种反转会在此坐标系中以 2 为增量改变距离，因此只能吸收松弛值。 这使得三角阈值加上奇偶校验条件既是充分必要的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def hex_dist(x, y):
    # axial coordinates to cube: (x, y, -x-y)
    z = -x - y
    return max(abs(x), abs(y), abs(z))

def solve():
    t = int(input())
    coords = [tuple(map(int, input().split())) for _ in range(t)]

    for x, y in coords:
        d = hex_dist(x, y)

        # find smallest k with k(k+1)/2 >= d
        k = 0
        s = 0
        while s < d:
            k += 1
            s += k

        if (s - d) % 2 == 0:
            print("Yes")
        else:
            print("No")

if __name__ == "__main__":
    solve()
```功能`hex_dist`将轴坐标转换为立方坐标并使用六角距离的标准最大范数表征。 这避免了遍历网格的任何需要。 

循环计算$k$是安全的，因为$k$只能长到大约$4.5 \cdot 10^4$对于最大距离$10^9$，它足够小$10^5$查询。 

最终的奇偶校验直接应用于三角和与所需距离之间的差。

 ## 边缘情况

 一个微妙的案例就是起源。 用于输入$(0,0)$，十六进制距离为零，所以$k=0$松弛为零。 该算法正确输出“是”，因为不需要移动。 

另一个重要的情况是距离为 1 的点，例如$(0,-1)$。 这里$k=1$,$S_1=1$，松弛为零，因此算法立即接受。 初始化三角累加时的任何错误都会错误地拒绝这一点。 

边界场景发生在以下情况：$d$例如，就在一个三角形数的下方$d = 5$。 然后$k=3$自从$S_2=3 < 5$和$S_3=6 \ge 5$。 松弛是$1$，奇偶校验失败。 这是三角环中经常出现差一误差的地方，因为停在$S_k > d$而不是$S_k \ge d$更改精确三角值的正确性。
