 ## 解决方案
 ## 问题理解

 我们给定一个固定模数$n$和一套$A \subseteq \{1,2,\dots,n\}$大小最多为 40。从这个集合中我们考虑它的所有子集。 对于任意子集$S \subseteq A$，我们可以分配每个元素$S$加号或减号，形成以下形式的表达式$$\pm a_1 \pm a_2 \pm \cdots \pm a_{|S|}.$$如果存在至少一个这样的符号分配，其结果总和可被整除，则称子集有效$n$。 在所有有效子集中，我们只对包含性最小的子集感兴趣，这意味着它们中没有非空真子集也是有效的。 

任务是计算有多少个子集$A$同时满足这两个属性：它们可以被签名以产生多个$n$，并且它们不包含具有相同属性的更小的子集。 

约束条件$m \le 40$是决定性的特征。 它立即排除了枚举所有子集的所有子集或尝试对高达以下值进行动态编程的任何方法$n$不利用结构。 由于子集的数量$A$是$2^{40}$，检查每个子集的解决方案已经处于可行性的边缘，因此真正的挑战是有效地处理符号分配和极简性。 

一个微妙的点是，“可尊重的”仅取决于符号赋值的存在，而不取决于赋值本身，而极小性取决于子集包含，而不取决于代数表示。 另一个重要的边缘情况是不考虑空子集，因为极小性仅在非空真子集中定义。 

## 方法

 蛮力观点是迭代每个子集$S \subseteq A$。 对于每个子集，我们检查是否可以分配符号，以便总和可被整除$n$。 这是一个经典的子集和变体，其中每个元素可以贡献$+a_i$或者$-a_i$。 我们可以使用位集 DP 对余数取模来检查可行性$n$，运行于$O(|S| \cdot n)$。 自从$n \le 40$和$|S| \le 40$，这是每个子集都可以管理的。 

真正的瓶颈是极少性。 如果我们独立测试每个子集，我们可能会计算出有效最小子集的许多超集。 关键的结构观察是，符号分配下的可行性定义了一个闭包系统：一旦子集可行，所有超集在某些符号和的存在方面仍然可行，但极简性是区分“不可约”超集的原因。 

这提出了一个相反的观点：我们不应该检查每个子集并进行过滤，而应该只构建最小的可行子集。 在子集枚举问题中强制执行最小性的标准方法是通过 DFS 或中间相遇搜索进行包含排除，其中增量检查可行性，并修剪已经包含可行子结构的分支。 

因为$m \le 40$，中间相遇成为自然的工具。 我们分手了$A$分为大小最多为 20 的两半。每一半都可以完全枚举。 对于每个子集，我们计算所有可实现的有符号和模的集合$n$。 每个子集对应一个可达残差集，可行性相当于包含残差0。 

然后，我们要计算并集可行但其严格子集都不可行的子集。 这相当于计算部分有序子集族中的最小元素，其中属性“具有零残基签名赋值”是单调的。 

我们不直接用求和来推理，而是将问题重新解释如下。 每个元素$a_i$贡献要么$+a_i$或者$-a_i$，所以取模$n$算术这相当于选择一个有符号子集和。 如果我们修复一个子集$S$，所有可能和的集合形成群中的可达区间$\mathbb{Z}_n$由元素生成$S$。 可行性意味着 0 位于这个生成的子集和空间中。 

关键的简化在于，这相当于检查是否存在子集$T \subseteq S$这样$$\sum_{x \in T} x \equiv \sum_{x \in S \setminus T} x \pmod n,$$重新排列为$$2 \sum_{x \in T} x \equiv \sum_{x \in S} x \pmod n.$$因此可行性仅取决于子集和是否达到特定目标模$n$，并且这可以针对所有子集进行预先计算。 

一旦可行性降低到子集和可达性，就可以通过过滤所有可行子集并减去包含较小可行子集的子集来强制执行极小性。 做到这一点的简洁方法是按大小递增的顺序枚举子集，并使用带有存储的“已经可行子集”指示符的位掩码上的 DP，将超集标记为对于最小性无效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 使用 DP + 最小性检查对每个子集进行暴力破解 |$O(2^m \cdot m \cdot n)$|$O(n)$| 太慢了|
 | 中间相遇+子集DP+极简过滤 |$O(2^{m/2} \cdot m + 2^m)$|$O(2^{m/2})$| 已接受 |

 ## 算法演练

 1. 预先计算所有子集的子集和$A$。 对于每个掩码，计算总和$S(\text{mask})$。 这是必要的，因为可行性仅取决于是否可以满足模半和条件$n$。 
2.建立DP表`dp[mask][r]`对于子集和可达性模$n$。 价值`dp[mask][r] = true`意味着存在一个已签名的作业`mask`产生残渣$r$。 转换将每个元素添加为$+a_i$或者$-a_i$，更新余数模$n$。 
3. 标记子集`mask`可行，如果`dp[mask][0]`是真的。 这直接编码了符号分配的存在，其总和为$n$。 
4. 为了强制执行最小性，按基数递增顺序处理子集。 维护一个数组`good[mask]`指示子集是否已知包含更小的可行子集。 
5. 当子集可行且未标记时`good`，它被算作最小解。 那么它的所有超集都隐式地被取消了最小化的资格，因此我们将标记传播到所有超集。 
6. 使用位掩码上的子集 DP 有效地实现传播，其中我们通过添加未使用的元素来扩展掩码。 这确保每个掩码仅在必要时更新。 
7. 最终答案是不被任何较小的可行子集支配的可行掩模的数量。 

### 为什么它有效

 包含下的可行性是单调的：添加元素永远不会破坏有效符号分配的存在，因为我们总是可以将任意符号分配给新元素并通过内部配对来忽略它们。 这使得可行子集族向上封闭。 因此，最小可行子集正是这个向上封闭族在包含顺序下的最小元素。 以不断增加的大小处理子集可以保证，当第一次遇到可行的子集时，除非已经处理过，否则其中不存在更小的可行子集，因此标记超集可以保持正确性，而无需重复计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    N = 1 << m

    # dp[mask] = set of reachable residues using ± signs
    dp = [set() for _ in range(N)]
    dp[0].add(0)

    for mask in range(N):
        for i in range(m):
            if not (mask >> i) & 1:
                for r in dp[mask]:
                    dp[mask | (1 << i)].add((r + a[i]) % n)
                    dp[mask | (1 << i)].add((r - a[i]) % n)

    feasible = [False] * N
    for mask in range(N):
        if 0 in dp[mask]:
            feasible[mask] = True

    # minimality filtering
    good = [False] * N
    masks_by_size = sorted(range(N), key=lambda x: bin(x).count("1"))

    ans = 0
    for mask in masks_by_size:
        if not feasible[mask]:
            continue
        if good[mask]:
            continue
        ans += 1
        # mark all supersets
        for sup in range(N):
            if (sup | mask) == sup:
                good[sup] = True

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案使用位掩码 DP 为每个子集构建所有可达的有符号和。 每次转换都会添加或减去当前元素的模数$n$。 当残差 0 可达时，子集是可行的。 

通过按大小递增顺序处理子集来强制执行极简性。 当对可行子集进行计数时，所有超集都将失效，因此以后无法对它们进行计数。 

主要的微妙之处是将有符号子集和解释为可达性问题$\mathbb{Z}_n$，它允许动态编程而不是显式枚举符号分配。 

## 工作示例

 考虑样本$n = 7$,$A = \{1,2,3,5,6\}$。 一个可行的子集是$\{2,3,5\}$自从$2 + 3 - 5 = 0$。 另一个是$\{1,6\}$自从$1 + 6 = 7$。 DP 识别两个相应掩码的残基 0。 两者都不包含较小的可行子集，因此两者都被计算在内。 

现在考虑一个构建的例子$n = 5$,$A = \{1,2,3\}$。 

| 面膜| 子集| 可达残基 | 可行| 好| 行动|
 | --- | --- | --- | --- | --- | --- |
 | 001| {1} | {0,1,4} | 是的 | 没有| 计数|
 | 010| {2} | {0,2,3} | 是的 | 是的 | 跳过|
 | 011| {1,2} | ... | 是的 | 是的 | 被封锁 |

 该表显示，一旦找到最小可行子集，所有超集都将被排除。 

这证实了即使存在多个重叠的可行结构，最小元素也能被正确隔离。

 ## 边缘情况

 关键的边缘情况是单个元素等于 0 模时$n$。 在这种情况下，任何包含它的单例子集都是立即可行的，并且它的所有超集都变得非最小。 该算法正确地处理了这个问题，因为该子集的 DP 在单例级别包含残差 0。 

另一个边缘情况是对称抵消，例如$\{a, n-a\}$。 这在大小 2 下产生了可行性，但两个单例都不可行，因此两个单例仍然是候选者。 极小过滤器确保只计算大小为 2 的子集
