 ## 解决方案
 ## 问题理解

 我们得到一个有向图，其中每个顶点都带有一个正整数标签。 从顶点开始的每条有向边\(u\)到一个顶点\(v\)贡献一个定义为\(\log_{a_u}(a_v)\)的权重。 有效路径是至少两个不同顶点的序列，其中每个连续对都由有向边连接。 路径的值是这些边权重的乘积，我们需要找到所有简单有向路径的最大可能值。 

结构很重要：虽然图可能包含循环，但有效路径不能重复顶点，因此我们总是处理简单路径。 每条边上的数量是乘法的，并且它通过具有可变基数的对数取决于两个端点。 

约束条件达到\(n, m \le 2 \cdot 10^5\)。 任何尝试枚举路径甚至对所有顶点对进行成对动态规划的解决方案都是立即不可行的。 即使\(O(n^2)\)转换已经太大了，任何涉及每个节点重复最短路径计算的事情都不会通过。 唯一可行的方向是在边缘上具有线性或近线性传播的图 DP。 

当存在循环时，会出现微妙的故障情况。 由于路径必须简单，因此我们不能像贝尔曼-福特那样进行幼稚的松弛，允许任意重新访问节点。 

考虑一个三角形循环：```
1 → 2 → 3 → 1
a1 = 2, a2 = 4, a3 = 8
```每条边贡献：\(\log_2 4 = 2\),\(\log_4 8 = 1.5\),\(\log_8 2 = 1/3\)。 

如果忽略“无重复顶点”约束，保持循环的简单算法会错误地放大值。 正确的答案必须来自一条简单的路径，而不是步行。 

另一个微妙的问题是数值稳定性。 由于答案是许多对数的乘积，因此值可能会快速缩小或增长，并且必须仔细控制浮动精度。 

## 方法

 暴力方法会尝试图中的每条简单路径，计算其边缘乘积，并取最大值。 这在概念上是正确的，因为定义直接涵盖所有简单路径。 然而，一般有向图中的简单路径的数量可以是指数级的\(n\)，在密集的 DAG 状结构中达到 \(O(2^n)\)。 即使存储或枚举它们也是不可能的，除非它们非常小\(n\)。 

为了减少这个问题，我们关注边权重的代数表现。 每条边贡献 \(\log_{a_u}(a_v)\)，可以使用自然对数重写：\[
\log_{a_u}(a_v) = \frac{\ln a_v}{\ln a_u}.
\]现在考虑一条路径\(v_1 \to v_2 \to \dots \to v_k\)。 其值变为：\[
\prod_{i=1}^{k-1} \frac{\ln a_{v_{i+1}}}{\ln a_{v_i}}.
\]这个表达望远镜。 所有中间条款取消：\[
\frac{\ln a_{v_2}}{\ln a_{v_1}} \cdot \frac{\ln a_{v_3}}{\ln a_{v_2}} \cdots \frac{\ln a_{v_k}}{\ln a_{v_{k-1}}}
= \frac{\ln a_{v_k}}{\ln a_{v_1}}.
\]因此整个路径权重仅取决于其端点，而不取决于内部结构。 

这是关键的结构崩溃：我们只关心顶点对，而不是搜索路径\(u \to v\)这样存在一条简单的路径\(u\)到\(v\)。 对于任何此类可达性，该对的最佳贡献固定为 \(\ln(a_v)/\ln(a_u)\)。 

于是问题就变成了：在有向图中所有可达对中，最大化\(\ln(a_v)/\ln(a_u)\)。 

这可以重新组织为最大化可达性约束的比率。 我们需要以一种跟踪每个可到达组件的最佳可能起始节点的方式来传播可达性。 

一种有用的解释是将每个节点视为携带从该节点开始的路径的候选值“最佳可能分母”。 如果我们按升序处理顶点\(a_v\)，我们可以传播可达性，同时在每个可达区域中保持尽可能小的 \(\ln(a_u)\)，因为最小化分母可以最大化比率。 

这导致了在拓扑上不相关但值排序的传播过程上的DP：我们对顶点进行排序\(a_v\)，并逐步激活它们，同时通过邻接结构维护可达性信息。 激活节点上的类似联合的传播或类似 BFS 的扩展会产生最佳的可达配对。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 暴力破解所有简单路径 | \(O(2^n)\) | \(O(n)\) | 太慢了|
 | 价值排序可达性 DP | \(O((n + m)\log n)\) | \(O(n + m)\) | 已接受 |

 ## 算法演练

 我们将问题转化为使用标签的对数，因为对数的比率定义了边缘贡献。 我们预先计算 \(w_v = \ln(a_v)\)。 

1. 将所有顶点按降序排序\(a_v\)，等效地减少\(w_v\)。 这种排序确保当我们将节点作为潜在端点处理时，所有具有较大标签的候选节点都已被考虑。 这一点至关重要，因为较大的终点值往往会主导比率。 

2. 维护一个跟踪哪些顶点已经“激活”的结构，这意味着它们可以作为所考虑路径的起点。 

3. 按排序顺序处理顶点。 激活顶点时\(v\)，我们允许边缘\(u \to v\)在哪里\(u\)已经处于活动状态以形成有效的转换。 对于每个这样的边，我们尝试更新结束于的最佳可达值\(v\)使用日志之间的关系。 

4. 对于每个活动边沿\(u \to v\)，计算候选值：\[
\frac{\ln(a_v)}{\ln(a_u)}.
\]我们在所有此类转变中保持全局最大值。 

5. 处理收到的捐款后\(v\)， 标记\(v\)处于活动状态，因此它可以作为排序顺序中未来顶点的源。 

每个步骤都确保当我们考虑一条边时，它的源已经被放置在与最佳分母一致的有效可达性上下文中。 

### 为什么它有效

 伸缩属性将每个简单路径折叠成仅由其端点组成的函数。 因此，除了可达性之外，路径的任何中间结构都是无关的。 按标签排序可确保当某个顶点被视为潜在端点时，路径起点的所有有效候选点都已被引入。 这保证了每个可达对在与最大化比率一致的方向上被精确地评估一次，并且不会构造无效的多次访问路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import math
from collections import defaultdict, deque

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    rg = [[] for _ in range(n)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        rg[v].append(u)

    # work with log values
    w = [math.log(x) for x in a]

    order = sorted(range(n), key=lambda i: w[i], reverse=True)

    active = [False] * n
    ans = 0.0

    # For each node as endpoint candidate in decreasing order
    for v in order:
        # try all incoming active edges
        for u in rg[v]:
            if active[u]:
                ans = max(ans, w[v] / w[u])

        active[v] = True

    # path must have at least 2 vertices, so ans already covers edges
    print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```该实现依赖于节点标签的预计算对数。 我们反转图，以便当我们将节点作为端点处理时，我们可以有效地检查所有潜在的前驱节点。 活动数组强制只有已处理的节点才能充当路径起点，这与排序顺序结构一致。 

该部门`w[v] / w[u]`与伸缩路径值完全对应。 所有此类可达对中的最大值就是答案。

按值递减排序的顺序是顶点 3、2、1。

 |---|---|---|---|---|---|---|

 ## 边缘情况

 一个关键的边缘情况是当循环存在但只有一些边缘应该起作用时。 在标签增加的 3 个循环中，该算法确保仅考虑已激活节点的边，因此不会发生无效的多步循环。 

另一种情况是最佳路径是直接边缘而不是长路径。 由于每个顶点最终都会被激活，并且在处理端点时所有传入边都会被检查一次，因此直接边仍会在其正确的上下文中进行评估并且不能被跳过。 

最后一种情况是严格减少或增加链条。 在这些图中，激活顺序确保在处理其端点时准确评估每条边，并且最大比率来自每条边的单次比较，而不是任何多步累积。
