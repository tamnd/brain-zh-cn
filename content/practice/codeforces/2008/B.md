 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，它最初是通过逐行压平矩形网格而形成的。 众所周知，网格是“美丽的”，这意味着它的边界单元都是`1`所有内部细胞都是`0`。 

任务不是重建网格，而是确定是否存在任何方法将字符串解释为来自方形网格，其中行数等于列数，同时仍然遵循相同的“边界一，内部零”结构。 

因此，从概念上讲，我们正在检查兼容性条件：我们是否可以将字符串放入`r × r`网格的周长全为 1，内部全为 0。 

关键的约束是字符串已经固定； 只有解释（维度`r`）是灵活的。 自从`r^2`必须等于字符串长度，问题实际上是询问长度是否是完美的正方形以及隐含的结构是否可以匹配有效的边框模式。 

由于测试的总输入长度很大，高达 2 · 10^5，因此每个测试用例的任何解决方案都必须是线性的。 任何涉及每次测试模拟多个候选网格的方法都会太慢。 

一个常见的错误是尝试显式重建矩阵或通过填充网格来测试多个可能的边长。 这会浪费计算并且是不必要的，因为方形边框的结构一旦确定就完全确定了`r`是固定的。 

## 方法

 蛮力的想法是尝试每一个可能的维度`r`从 1 到`n`，检查是否`r × r = n`，如果是，则重建网格并验证它是否与有效的 border-ones 模式匹配。 这种方法已经基本上是多余的，因为只有一个`r`可以满足平方条件，但即使推广到尝试多个候选，它仍然需要构建或模拟一个矩阵并检查所有单元，这在最坏的情况下是 O(n√n)。 

关键的观察是，仅当长度为完全平方时才存在方阵。 一旦成立，一个美丽矩阵的结构就固定了：所有第一行和最后一行都是 1，所有第一列和最后一列都是 1，其他所有内容都是零。 一旦尺寸已知，该模式就不会引入任何歧义。 所以整个问题就简化为检查字符串长度是否是完全平方数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力重建| O(n√n) | O(n√n) | O(n) | 太慢了|
 | 仅方格支票 | 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们只需要判断字符串的长度是否可以组成一个方格即可。 

1.读取整数`n`和字符串`s`。 字符串本身的使用不会超出其长度。 
2. 计算整数平方根`n`。 
3. 检查该整数根的平方是否准确返回`n`。 
4. 如果匹配，则输出“Yes”，否则输出“No”。 

第 3 步背后的原因是，有效的方格网格恰好需要`r × r`细胞，所以长度必须是完全平方数。 

### 为什么它有效

 一个正方形的美丽矩阵完全是由它的大小决定的`r`。 如果字符串长度不是以下形式`r^2`，无论 1 和 0 的排列如何，都不可能存在方形网格。 如果它是一个完美的正方形，那么对于该尺寸总是可以构造有效的边界配置，因此存在仅取决于算术条件。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    r = int(math.isqrt(n))
    if r * r == n:
        print("Yes")
    else:
        print("No")
```实现仅关注长度`n`。 该字符串仍会被读取以正确使用输入，但从未被处理。 关键细节是使用`math.isqrt`，这避免了可能出现的浮点精度问题`sqrt`。 

一个常见的陷阱是在读取字符串时忘记去除换行符； 虽然此处没有严格要求，但确保一致的输入处理是一种很好的做法。 另一个微妙的问题是使用浮点平方根和转换，这可能会由于精度误差而对大的完美平方进行错误分类。 整数平方根完全避免了这种情况。

 ## 边缘情况

 唯一有意义的边缘情况是当`n`非常接近完美平方，例如`8`或者`10`。 在这些情况下，`isqrt(n)`返回地板根，并且正确地平方它无法匹配`n`，确保答案是“否”。 这可以避免浮点舍入产生的任何歧义，并保证即使对于大输入也能保持正确性。
