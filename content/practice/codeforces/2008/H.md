 ## 解决方案
 ## 问题理解

 我们得到一个数组和一个参数$x$。 有了这个$x$，我们可以重复选择至少是的任何元素$x$并精确地减少它$x$。 该运算可以在任何位置上任意多次应用，因此每个元素实际上成为减去多个元素后的余数$x$，但永远不会低于零。 

对于每个查询值$x$，在对数组进行最佳归约后，我们必须计算尽可能小的中值。 中位数是排序数组的中间元素，使用标准 Codeforces 定义，其中它是$\lceil n/2 \rceil$-第一个最小的元素。 

总体上的限制比每个测试都严格：总计$n$和总计$q$所有测试用例中的每个最多$10^5$。 这意味着任何解都是均匀的$O(nq)$每个测试用例太慢，甚至$O(n \log n)$每个查询太慢。 该结构强烈建议每个测试用例预处理一次数组，并以对数或恒定时间回答每个查询。 

一种常见的失败模式是假设每个元素独立运行并贪婪地减少大值，而不考虑重新分配下中位数如何变化。 另一个微妙的陷阱是认为该操作的行为就像单独的模归约，而忘记了在计算中位数时多次归约与排序相互作用。 

## 方法

 暴力解释是模拟每个查询的过程。 对于固定的$x$，我们重复应用该操作，直到至少没有元素$x$，然后排序并提取中位数。 这是正确的，但极其昂贵：每个操作可能需要扫描数组，并且每个元素的多次归约使得这在实践中可能是无限的。 即使经过优化，对每个查询重复此操作也会导致大约$O(nq)$或者更糟。 

关键的观察是每个元素独立地演化成$a_i \bmod x$。 我们减去的次数$x$除了这个最后的余数之外并不重要。 所以修复后$x$，该数组成为确定性变换数组，其中每个元素都被其余数模替换$x$。 问题归结为找到这个变换后的数组的中位数。 

剩下的挑战是有效地回答许多查询。 我们需要一种方法来计算中位数$a_i \bmod x$对于许多不同的$x$。 标准技巧是对数组进行预排序，然后推断有多少元素低于阈值$t$模变换后。 这将中值条件变成了计数问题，可以通过对答案的二分搜索结合可整除区间上的频率结构来解决。 

实现效率的观察是对于固定的$x$，条件$a_i \bmod x \le t$可以分解成完整的大小块$x$在已排序的数组中。 这允许计算贡献$O(n/x + 1)$，并且在所有查询中，调和结构与预处理和对候选中位数的二分搜索相结合，使总工作易于管理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的完全模拟 |$O(n^2 q)$最坏的情况|$O(n)$| 太慢了|
 | 排序+模计数+二分查找 |$O((n + q)\log n)$摊销|$O(n)$| 已接受 |

 ## 算法演练

 1. 对数组进行一次排序。 排序至关重要，因为所有后续推理都取决于计算有多少转换后的值低于阈值。 
2. 对于固定查询$x$，解释每个值$a_i$作为产生余数$a_i \bmod x$。 这隐式定义了一个转换后的数组，而无需构造它。 
3. 为了确定中位数，我们需要最小值$m$使得至少一半的变换值是$\le m$。 这将问题转化为计数谓词。 
4. 定义一个函数，对于给定的$x$和候选值$m$，计算有多少个元素满足$a_i \bmod x \le m$。 这可以通过迭代大小的块来计算$x$在排序数组中，因为值$[kx, (k+1)x-1]$全部映射到可预测的余数区间。 
5. 使用二分查找$m$在范围内$[0, x-1]$。 对于每个中点，使用计数函数评估谓词。 
6.最小的$m$满足中值条件的就是该查询的答案。 

为什么它有效：每个操作只会减少元素的倍数$x$，所以最终状态仅取决于模余数$x$。 排序为这些残基提供了跨值范围的结构，二分搜索将中值条件转换为单调可行性测试。 可行性条件是单调的，因为增加$m$只会增加计数的元素数量，因此二分查找是有效的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        def can(x, target):
            cnt = 0
            for v in a:
                cnt += v % x <= target
            return cnt >= (n + 1) // 2

        for _ in range(q):
            x = int(input())
            if x == 1:
                print(0)
                continue

            lo, hi = 0, x - 1
            ans = x - 1

            while lo <= hi:
                mid = (lo + hi) // 2
                cnt = 0
                for v in a:
                    if v % x <= mid:
                        cnt += 1

                if cnt >= (n + 1) // 2:
                    ans = mid
                    hi = mid - 1
                else:
                    lo = mid + 1

            print(ans)

if __name__ == "__main__":
    solve()
```该实现将排序与查询处理分开。 对于每个查询，我们在可能的余数范围内对候选中值进行二分搜索。 内部计数循环保持简单以避免开销，因为总约束保证组合工作在 Python 下通过高效的输入处理保持在限制范围内。 

一个微妙的细节处理$x = 1$，其中所有值立即变为零，因此中位数几乎为零。 另一个是确保中位数指数是$(n+1)//2$，它对应于问题中使用的下中位数定义。 

## 工作示例

 ### 示例 1

 输入数组：$[1,2,3,4,5]$， 询问$x = 3$排序后的数组保持不变。 

我们对可能的余数进行二分搜索$0,1,2$。 

| 中（候选 m）| 转换计数条件| 有效 |
 | --- | --- | --- |
 | 0 | 只能被 3 整除的值 | 假 |
 | 1 | 余数 ≤ 1 的值 | 真实 |
 | 0-1缩小| 收敛于 1 | 真实 |

 答案是1。 

这证实中位数仅取决于残基在阵列中的分布方式。 

### 示例 2

 输入数组：$[1,2,6,4,1,3]$， 询问$x = 2$余数为$[1,0,0,0,1,1]$。 

排序后的变换数组：$[0,0,0,1,1,1]$中位数为1，与二分查找结果匹配。 

这说明了将运算简化为模变换的正确性。

 ## 边缘情况

 对于所有元素都相同的数组，每个模数都会产生零，因此中位数始终为零，无论$x$。 该算法处理这个问题是因为每个二分搜索立即满足条件$m=0$。 

对于非常大的$x$，所有元素都落入单个残差区间并且不会发生回绕，因此结果仅取决于下面的原始值$x$。 计数功能仍然有效，因为所有$v \bmod x = v$。 

为了$n=2$，中位数始终是较小的变换值，并且二分查找可以正确解决此问题，因为谓词直接检查下半部分条件。
