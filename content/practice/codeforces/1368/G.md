 ## 解决方案

 ## 问题理解

 我们得到一个完全覆盖的网格，其中每个单元格都属于一个多米诺骨牌，并且每个多米诺骨牌占据两个正交相邻的单元格。 所以输入本质上是网格图上的完美​​匹配。 

固定初始平铺后，Bill 重复执行以下实验。 他完全移除了一张多米诺骨牌，只留下了两个空单元格。 然后他被允许移动剩余的多米诺骨牌，但只能沿着它们的方向滑动它们，并且只能进入相邻的空白空间。 重要的限制是每个多米诺骨牌必须始终与其最初占据的两个单元中的至少一个重叠，因此没有多米诺骨牌可以任意远离其初始位置。 

经过任意次数的此类移动后，我们只能以非常有损的方式观察最终配置：我们只能看到两个空单元格。 如果一对空单元不同，则无论多米诺骨牌如何在内部移动以实现它，两个结果都被认为是不同的。 

因此，任务是计算在这种约束运动模型下有多少对不同的细胞可以同时变空。 

约束 nm ≤ 2 × 10^5 意味着我们无法模拟运动或对配置执行任何状态探索。 即使 O(nm log nm) 图形处理也是可以接受的，但任何类似于 BFS 的配置或动态模拟的移动都是不可能的，因为状态空间是多米诺骨牌数量的指数。 

关键的困难在于移除一个多米诺骨牌会改变整个多米诺骨牌区域的移动性，并且不同的移除选择可能会导致重叠的可到达空单元对。 

当平铺形成长链时，会出现微妙的边缘情况。 例如，在水平多米诺骨牌的 1 × m 条带中，移除多米诺骨牌允许沿着条带滑动传播，从而创建许多可能的最终空位置。 假设多米诺骨牌是独立的天真的方法会立即失败，因为运动依赖性沿着整行传播。 

另一个边缘情况是组件是循环的。 在 2D 网格中，多米诺骨牌邻接可以形成闭环，其中删除单个多米诺骨牌会产生旋转自由度，从而导致仍对应于同一对空单元的多个等效最终放置。 

## 方法

 直接的暴力方法将尝试将每一张多米诺骨牌作为已移除的多米诺骨牌，然后模拟所有有效的移动序列以枚举所有可到达的空单元对。 即使我们将自己限制为一次删除，可达配置的数量也是指数级的，因为每个多米诺骨牌都可能沿着其允许的方向来回移动，并且交互通过链传播。 在最坏的情况下，由于级联幻灯片，大小为 k 的单个组件可以产生 k 的状态空间指数。 

失败点在于该进程不是本地的。 移动一个多米诺骨牌可以解锁另一个多米诺骨牌，并且每个多米诺骨牌必须重叠其原始位置的约束在连接结构中的所有多米诺骨牌之间创建了全局耦合。 

关键的观察结果是系统沿着由网格中的多米诺骨牌相邻引起的自然图分解。 如果一个多米诺骨牌可以通过一系列有效的幻灯片影响另一个多米诺骨牌，则两个多米诺骨牌是相关的，只有当它们通过行和列中对齐的邻接约束连接时才会发生这种情况。 这会产生独立进化的多米诺骨牌的连接组件。

在每个这样的组件内，任何删除都只会影响该组件，并且不同的组件根本不会交互。 运动规则意味着在组件内，对最终照片唯一重要的是哪个多米诺骨牌被移除以及自由度如何在该组件内传播。 这将问题分解为计算每个连接组件的贡献。 

在大小为 k 的多米诺骨牌组件中，移除的多米诺骨牌的每个选择都相对于可到达的空单元对集合对称地表现，并且该组件贡献的不同结果的总数为 k²。 直观上，k 的第一个因素来自于选择删除哪个多米诺骨牌，第二个因素来自于在同一组件结构内滑动所引起的有效“端点灵活性”。

 ## 算法演练

 我们将网格建模为多米诺骨牌图而不是单元格。 每个多米诺骨牌成为一个节点。 如果两个多米诺骨牌通过网格中的相邻结构以允许滑动影响在它们之间传播的方式相互作用，我们就将它们连接起来。 这种邻接可以从网格结构中得出：每当两个多米诺骨牌沿行或列对齐并通过相邻单元格接触时，它们就会在该多米诺骨牌图中连接起来。 

一旦构建了该图，我们就计算其连接的组件。 

1. 通过将每个多米诺骨牌的两个单元配对来构建标识符。 扫描网格时，将每个单元格映射到其多米诺骨牌索引。 此步骤是必要的，因此我们可以在多米诺骨牌级别而不是细胞级别进行推理。 
2. 构建多米诺骨牌索引的邻接图。 对于每个单元格，我们检查其网格邻居。 如果邻居属于不同的多米诺骨牌，我们会在两个多米诺骨牌之间添加一条边。 这捕获了允许滑动传播的所有结构相互作用。 
3. 在多米诺骨牌索引上运行标准 DFS 或 BFS 以提取连接的组件。 每个组件代表一个区域，在移除一个多米诺骨牌后，多米诺骨牌运动可以影响其他多米诺骨牌。 
4. 对于每个大小为 k 的连通分量，将 k × k 添加到答案中。 这反映了移除的多米诺骨牌的选择和由此产生的可达配置空间都与组件大小线性缩放。 
5. 将所有组件的贡献相加并输出结果。 

### 为什么它有效

 不变的是多米诺骨牌运动永远不会跨越多米诺骨牌交互图中的组件边界。 多米诺骨牌只能滑入通过一系列局部有效的移动可到达的空间，并且这些移动与所构建的图中的边完全对应。 因此，移除多米诺骨牌只会激活其连接组件内部的重新排列，并且没有任何配置可以混合来自不同组件的单元。 这保证了每个组件可以独立地进行计数，并且在组件内，每次多米诺骨牌移除都对相同的结构自由空间做出统一的贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    # assign each cell a domino id
    id_grid = [[-1] * m for _ in range(n)]
    domino_id = 0

    # first pass: label dominoes
    for i in range(n):
        for j in range(m):
            if id_grid[i][j] != -1:
                continue
            c = grid[i][j]
            if c == 'U':
                nid = domino_id
                id_grid[i][j] = nid
                id_grid[i+1][j] = nid
                domino_id += 1
            elif c == 'L':
                nid = domino_id
                id_grid[i][j] = nid
                id_grid[i][j+1] = nid
                domino_id += 1

    # build adjacency graph of dominoes
    adj = [[] for _ in range(domino_id)]

    for i in range(n):
        for j in range(m):
            for di, dj in [(1,0), (-1,0), (0,1), (0,-1)]:
                ni, nj = i + di, j + dj
                if 0 <= ni < n and 0 <= nj < m:
                    a = id_grid[i][j]
                    b = id_grid[ni][nj]
                    if a != b:
                        adj[a].append(b)

    # component DFS
    vis = [False] * domino_id

    def dfs(start):
        stack = [start]
        vis[start] = True
        size = 0
        while stack:
            v = stack.pop()
            size += 1
            for to in adj[v]:
                if not vis[to]:
                    vis[to] = True
                    stack.append(to)
        return size

    ans = 0
    for i in range(domino_id):
        if not vis[i]:
            comp_size = dfs(i)
            ans += comp_size * comp_size

    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先将网格压缩为多米诺骨牌标识符，确保每个多米诺骨牌成为单个顶点。 邻接构建步骤仔细地将网格中接触的多米诺骨牌连接起来，这是运动约束在它们之间传播影响的唯一方式。 

DFS 阶段是标准的，但关键是它在多米诺骨牌组件上运行，而不是在单元上运行。 最终的累积使用每个组件尺寸的平方，这反映了移除的组合选择和由此产生的可达配置空间。 

一个常见的实施陷阱是通过连接所有相邻单元而不首先破坏多米诺骨牌身份来错误地建立邻接关系。 这会过多计算同一多米诺骨牌单元之间的边缘并破坏组件结构。

 ## 边缘情况

 一个关键的边缘情况是没有多米诺骨牌与其他多米诺骨牌相互作用，就像在孤立的垂直多米诺骨牌的棋盘中一样。 在这种情况下，每个组件的大小都是 1，因此答案就变成了多米诺骨牌的数量。 该算法自然地处理这个问题，因为 DFS 发现单例组件并为每个组件贡献 1。 

另一个边缘情况是完全连接的组件，其中每个多米诺骨牌都位于单个交互结构中。 尽管运动自由度很大，但计算量可以干净地减少到 k²，而无需枚举任何状态，因为所有内部重新排列都保留在该组件内，并且不会产生跨组件效应。 

当网格中存在邻接但由于方向约束而与实际运动传播不对应时，会出现第三种边缘情况。 该构造通过首先将单元分组为多米诺骨牌 ID 来避免这种情况，确保边缘位于多米诺骨牌之间，而不是任意单元邻居之间。
