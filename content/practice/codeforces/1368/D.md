 ## 问题理解

 我们得到一个整数列表，每个整数最多 20 位。 我们可以重复选择两个位置并应用按位转换，将一个数字的位推入另一个数字：一个数字成为该对的按位与，另一个成为按位或。 

每个操作都会保留整个数组中每个位位置处的设置位总数，因为对于任何固定位，成对变换不会更改两个所选数字中该位中存在的个数。 

执行任意数量的此类操作后，我们计算所有结果数字的平方和并希望最大化它。 

输入大小最多允许 200,000 个数字，每个数字最多 20 位。 这立即表明任何模拟对运算的方法都是不可能的，因为即使是对对的单个二次过程也会太慢。 我们需要 n 中更接近线性或线性的值，可能乘以位数。 

关键的困难在于操作不仅仅重新排列值，它们还以受约束的方式不断地重新分配位。 最终的配置不是任意的，但它足够灵活，主要任务变成决定如何将位集中到数字中以最大化平方和。 

一个天真的错误是假设对数组进行排序或贪婪地组合大量数字就足够了。 例如，考虑值`[1, 2, 4]`。 任何本地配对策略都可能首先组合大值，但最佳结果取决于分配比特贡献而不是大小。 另一种失败情况是假设数字的多重集被保留或仅被排列。 该操作明显改变了值，因此这种方法错过了实际的自由度。 

另一个微妙的问题是假设由于 AND 减少了值而 OR 增加了值，因此我们应该始终推动单个元素中 OR 的最大化。 虽然方向是正确的，但如果不了解每比特守恒，这会导致错误的贪婪合并决策。 

## 方法

 暴力方法将模拟对之间所有可能的操作，直到收敛。 每个操作都会更改两个值，并且该过程可以继续无限数量的步骤。 即使限制长度为 k 的序列，状态空间也是指数的，因为每个数字都是 20 位状态并且有 n 个。 这立即变得不可行。 

关键的观察是停止从整数的角度思考，而是独立地检查每一位。 对于任何固定的位位置，数组中的个数永远不会改变。 这意味着每一位 k 都贡献了必须分布在最终数字中的 cnt_k 个。 

因此，问题变成了重新分配任务：我们必须将这些位贡献分配给数字，以便将每个位 k 准确地分配给 cnt_k 个数字，并且我们希望最大化结果整数的平方和。 

现在结构变得更加清晰了。 平方强烈奖励集中力。 将多个高位放入同一个数字是有益的，因为平方中的交叉项会放大值。 例如，将位 2^18 和 2^17 组合在一个数字中比将它们分开产生更大的增益。 

因此，我们希望尽可能不均匀地将位打包成数字，同时考虑到每个位都有固定数量的副本。 

标准的贪婪构造是增量构建数字，始终将下一个可用位分配给当前最小的数字。 这确保了我们不断平衡负载，同时仍然允许随着较小的数字逐渐填充并随后有资格积累更高的位而自然出现高位集中。 

干净的实现使用当前值的最小堆。

 ## 算法演练

 我们从最高到最低处理位，以便在对平方影响最大时将较大的贡献放在第一位。 

1. 计算当前每个位包含多少个数字。 对于每个位位置 k，计算 cnt[k] 作为具有该位集的数组元素的数量。 该值在操作期间永远不会改变，因为每个位的总计数是不变的。 
2. 初始化一个包含所有 n 个数字的最小堆，从零开始。 每个堆元素代表正在构造的数字的当前值。 
3. 对于从19到0的每个位位置k，重复分配该位cnt[k]次。 每次分配都会从堆中获取当前最小的数字，向其添加 2^k，然后将其推回原处。 选择最小元素的原因是，在小基数上添加高位可以增加边际效益，从而最大限度地提高未来二次增益的潜力。 
4. 处理完所有位后，计算所有最终数字的平方和。

正确性来自于这样的不变性：在每一步中，我们都维护有效的位部分分配，其中每个位 k 恰好使用 cnt[k] 次，并且在所有此类部分分配中，堆策略使分配尽可能保持平衡。 这种平衡允许高位堆叠在一起，而不会以次优方式过早地过载单个数字。 由于平方奖励集中度，因此该过程有效地模拟了比特权重到箱中的最佳打包。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    cnt = [0] * 20
    for x in a:
        for b in range(20):
            if x >> b & 1:
                cnt[b] += 1

    heap = [0] * n
    heapq.heapify(heap)

    for b in range(19, -1, -1):
        for _ in range(cnt[b]):
            x = heapq.heappop(heap)
            x += (1 << b)
            heapq.heappush(heap, x)

    ans = 0
    for x in heap:
        ans += x * x

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先将输入压缩为每比特计数，这是在任意操作后仍然相关的唯一信息。 堆代表了最终数字的不断演变的结构。 每次分配一个位时，我们都会故意选择当前最小的数字以保持平衡，同时仍然允许随着时间的推移将多个位累积到单个元素中。 

从高到低处理位可确保在其对平方的结构影响最显着时尽早放置较大的贡献。 

## 工作示例

 考虑一个小的概念示例：`n = 3`, 值`[1, 2, 4]`。 位计数对于位 0、1 和 2 各出现一次。 

我们初始化堆`[0, 0, 0]`。 

处理完位 2 后：

 | 步骤| 堆状态 | 行动|
 | ---| ---| ---|
 | 1 | [0, 0, 0] | 将 4 分配给最小的 |
 | 2 | [0, 0, 4] | |

 处理完位 1 后：

 | 步骤| 堆状态| 行动|
 | ---| ---| ---|
 | 1 | [0, 0, 4] | 将 2 分配给最小的 |
 | 2 | [0,2,4]| |

 处理完位 0 后：

 | 步骤| 堆状态 | 行动|
 | ---| ---| ---|
 | 1 | [0,2,4]| 将 1 分配给最小的 |
 | 2 | [1,2,4]| |

 最终总和是`1 + 4 + 16 = 21`。 

该轨迹显示了如何在逐渐构建结构化值的同时独立分配每个位。 

现在考虑具有重复位的情况：`a = [3, 5]`。 二进制是`011`和`101`。 我们在位 0 中有两个 1，在位 1 中有一个，在位 2 中有一个。 

我们从`[0, 0]`。 

位 2 之后：

 | 堆| 行动|
 | ---| ---|
 | [0, 4] | 分配位 2 |

 位 1 之后：

 | 堆| 行动|
 | ---| ---|
 | [2, 4] | 分配位 1 |

 位 0 之后：

 | 堆| 行动|
 | ---| ---|
 | [3, 5] | 分配两个 |

 最终总和是`9 + 25 = 34`。 

这演示了较高位如何塑造早期结构，而较低位如何细化最终分布。

 ## 边缘情况

 n 等于 1 的最小输入不包含任何操作。 该算法正确返回单个值的平方，因为堆仅包含一个元素并且不会发生赋值。 

全零的情况测试位计数和堆初始化是否保持中性。 由于所有 cnt[b] 均为零，因此堆保持不变，最终总和为零，符合预期。 

所有数字都相同的情况检查对称性不会破坏贪婪分配。 即使存在多个相同的候选者，堆操作也会统一对待它们，并且最终配置仍然尊重总位计数，确保正确聚合为平方和。
