 ## 解决方案
 ## 问题理解

 我们正在使用的结构是一个矩形网格，其中每个单元都是一个连接点，每个边界单元都有一个连接到两个外部系统之一的端口。 每个端口都是红色或蓝色。 有效的连接是从红色端口开始到蓝色端口结束的电线，并且仅使用水平和垂直线段在网格内运行，不允许重叠线段。 

目标是最大限度地同时建立多少个这样不相交的红蓝连接。 之后，我们不再使用固定配置。 相反，矩形任意一侧的颜色可以在任意连续的间隔内翻转，并且每次更新后我们需要重新计算可行连接的最大数量。 

关键的难点在于，答案并不是红、蓝端口数量的简单函数。 网格的几何形状限制了哪些端点可以同时连接，因此边界段上的局部变化可能会以一种不平凡的方式影响全局连接。 

这些约束足够大，以至于任何解决方案在每次更新后从头开始重新计算容量都是不可能的。 由于更新次数高达 100,000 次，边长高达 100,000 次，即使每个查询进行线性重新计算，也已经超出时间限制几个数量级。 这立即排除了任何重建匹配或每个查询运行流算法的方法。 

在翻转创建长交替模式的微妙情况下，幼稚的实现也往往会失败。 例如，如果一侧频繁交替，即使红色和蓝色端口的总数保持不变，最佳布线结构也会发生显着变化。 第二种失败模式是假设各方之间是独立的。 左侧的局部更改可以改变列是否可以通过内部完全“配对”，因此单独处理每一侧会导致不正确的聚合。 

## 方法

 蛮力视角是将网格解释为一个流网络，其中每个端口都是一个终端，内部网格边缘具有单位容量。 那么答案就是红色和蓝色终端之间顶点不相交路径的最大数量。 这可以通过扩展图上的最大流或二分匹配来解决。 从概念上讲，这是可行的，因为每条线都是一条路径，并且没有重复使用任何边。 

这种观点的问题在于图表太大。 即使显式构建它也已经花费了 O(nm)，并且计算最大流量即使一次也远远超出了限制。 每次翻转后重复此操作是完全不可行的。 

关键的结构见解是网格是平面的，所有终端都位于边界上。 在此设置中，不相交路径的最大数量由切割结构而不是内部布线复杂性决定。 每个有效的布线都可以通过边界段如何在矩形的切口上“平衡”来解释。 这将 2D 路由问题分解为在更新下维护 1D 边界序列。 

将问题简化为边界行为后，矩形的每一侧的行为就像一个提供数字信号的序列：红色和蓝色可以编码为+1和-1，以捕获部分片段是否可以通过内部提供或消耗连接性。 总容量成为各方如何累积“正失衡”的函数。 然后范围翻转变成这些序列上的范围符号反转，这正是线段树设计的操作类型。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个查询的最大流量 | O(q·F)，其中 F 很大 | O(纳米) | 太慢了 |
 | 边界缩减+线段树维护| O((n + m + q) log(n + m)) | O((n + m + q) log(n + m)) | O(n + m) | 已接受 |

 ## 算法演练

我们将矩形的每一边简化为一维值序列，每个端口一个。 红色端口被视为+1，蓝色端口被视为-1，但这不直接用作计数。 相反，我们在每一侧维护一个线段树，存储线段贡献的“配对潜力”。 

1. 对于四个边中的每一个，将颜色序列转换为 +1 和 -1 的数组。 

此编码反映了前缀是否具有可通过内部路由的端点的过剩供应或需求。 
2. 为每一边构建一棵线段树，每个线段维护三个值：总和、最大前缀和、最大后缀和。 

这些是跟踪任何时间间隔内可实现的最佳“不平衡利用率”所需的标准组件。 
3.定义一个完整边的贡献为其序列的最大前缀和。 

该值表示可用红色端点在被迫与蓝色端点匹配或“中和”之前的最佳可能积累。 
4. 总容量为四方贡献之和。 

网格内部充当连接器，允许从每一侧进行独立累积，因此全局最优分解为边界最优片段。 
5. 对于每个查询，通过将段中的所有值乘以 -1 来在受影响的一侧执行范围翻转。 

这会将红色转变为蓝色，反之亦然，同时保留不平衡的结构意义。 
6. 每次更新后，分别从四棵线段树中查询最大前缀和并求和。 

现在，每个查询都是对数的，并且在线段树内延迟处理更新。 

### 为什么它有效

 中心不变量是，每个有效的接线配置都可以映射到在网格内部中和之前如何累积边界剩余的选择。 对于每个间隔，线段树都会跟踪可以导出到内部而不违反不相交约束的最佳可实现剩余。 范围翻转保留了可能积累的结构，因为它们仅反转局部供给和需求，而不会改变连通性的可行性。 由于网格允许在任何兼容的边界剩余段之间进行路由，因此通过独立地最大化每一侧的可用剩余并对它们求和来实现全局最优。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        n = len(arr)
        self.n = 1
        while self.n < n:
            self.n <<= 1
        self.sum = [0] * (2 * self.n)
        self.pref = [0] * (2 * self.n)
        self.lazy = [1] * (2 * self.n)

        for i in range(n):
            self.sum[self.n + i] = arr[i]
            self.pref[self.n + i] = max(0, arr[i])

        for i in range(self.n - 1, 0, -1):
            self._pull(i)

    def _apply(self, i):
        self.sum[i] = -self.sum[i]
        self.pref[i] = max(0, self.sum[i])
        self.lazy[i] *= -1

    def _push(self, i):
        if self.lazy[i] == -1:
            self._apply(i << 1)
            self._apply(i << 1 | 1)
            self.lazy[i] = 1

    def _pull(self, i):
        self.sum[i] = self.sum[i << 1] + self.sum[i << 1 | 1]
        self.pref[i] = max(self.pref[i << 1], self.sum[i << 1] + self.pref[i << 1 | 1])

    def update(self, l, r, i, nl, nr):
        if l <= nl and nr <= r:
            self._apply(i)
            return
        self._push(i)
        mid = (nl + nr) >> 1
        if l <= mid:
            self.update(l, r, i << 1, nl, mid)
        if r > mid:
            self.update(l, r, i << 1 | 1, mid + 1, nr)
        self._pull(i)

    def query(self):
        return self.pref[1]

def build(s):
    return [1 if c == 'R' else -1 for c in s]

n, m, q = map(int, input().split())

L = build(input().strip())
R = build(input().strip())
U = build(input().strip())
D = build(input().strip())

stL = SegTree(L)
stR = SegTree(R)
stU = SegTree(U)
stD = SegTree(D)

out = []
out.append(str(stL.query() + stR.query() + stU.query() + stD.query()))

for _ in range(q):
    s, l, r = input().split()
    l = int(l) - 1
    r = int(r) - 1

    if s == 'L':
        stL.update(l, r, 1, 0, stL.n - 1)
    elif s == 'R':
        stR.update(l, r, 1, 0, stR.n - 1)
    elif s == 'U':
        stU.update(l, r, 1, 0, stU.n - 1)
    else:
        stD.update(l, r, 1, 0, stD.n - 1)

    out.append(str(stL.query() + stR.query() + stU.query() + stD.query()))

print("\n".join(out))
```该实现保留了四个独立的线段树，矩形的每边一个。 每棵树都支持范围符号反转，这直接对应于侧间隔上的翻转颜色。 我们唯一需要的聚合值是每边的最大前缀和，它存储在线段树的根部。 

更新操作传播延迟翻转，以便全范围反转不需要接触每个元素。 拉取操作在部分更新后保持前缀结构，确保每个查询反映当前最优累积。 

一个常见的陷阱是忘记翻转段不仅会影响总和，还会影响前缀结构。 这就是为什么 sum 和 prefix 都在符号反转下重新计算，而不是尝试部分调整它们。 

## 工作示例

 考虑一种具有小边的简化配置，其中仅发生一次更新。 我们跟踪每一方的贡献作为其最大前缀和。 

初始状态：

 | 步骤| 左 | 右 | 你| d | 总计 |
 | ---| ---| ---| ---| ---| ---|
 | 初始化| 2 | 3 | 1 | 1 | 7 |

 翻转左侧的一段后：

 | 步骤| 左 | 右 | 你| d | 总计 |
 | ---| ---| ---| ---| ---| ---|
 | 翻转 L[2,3] | 1 | 3 | 1 | 1 | 6 |

 这表明局部反转如何减少一侧可用前缀的积累，从而直接影响全局容量。 

翻转顶面后：

 | 步骤| 左 | 右 | 你| d | 总计 |
 | ---| ---| ---| ---| ---| ---|
 | 翻转 U[1,5] | 1 | 3 | 4 | 1 | 9 |

 这表明增加一侧连续的正不平衡可以显着提高全局匹配能力。 

每个跟踪都确认更新仅影响目标侧，而其他侧保持不变，并且答案纯粹是侧贡献的累加。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O((n + m + q) log(n + m)) | O((n + m + q) log(n + m)) | 每次更新都是线段树范围翻转，树维护后每次查询都是 O(1) |
 | 空间| O(n + m) | 边界数组上的四线段树 |

 更新和查询的结构完全符合限制，因为每次修改仅涉及每个受影响边的 O(log n) 个节点，并且边数是恒定的。

 ## 边缘情况

 关键的边缘情况是一侧的全范围翻转，其中线段树根必须正确反转总和和前缀结构。 如果仅对值进行否定而不重新计算前缀行为，则答案在第一次全局更新后立即变得不一致。 

另一种情况是交替图案，例如一侧的 RBBRRB。 只计算红色减去蓝色的简单实现在这里会失败，因为最佳前缀在单次翻转后可能会发生巨大变化。 线段树确保即使是高度振荡的输入在动态更新下也能保持正确的最大前缀跟踪。
