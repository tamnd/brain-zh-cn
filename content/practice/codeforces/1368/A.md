 ## 解决方案
 ## 问题理解

 我们从两个正整数开始，`a`和`b`。 在一项操作中，我们可以将一个变量添加到另一个变量中：`a += b`或者`b += a`。 

每次操作仅更改一个值。 我们的目标是使两个数字中至少有一个严格大于给定的限制`n`。 对于每个测试用例，我们必须找到所需的最少操作数。 

就测试数量而言，约束很小，最多 100 个案例，但值本身可以大到`10^9`。 这立即表明我们不应该通过搜索或动态编程来模拟所有可能的选择序列。 即使每次移动的分支因子为 2，也会发生爆炸。 我们需要一个直接的策略。 

一个有用的观察是数字增长得非常快。 如果我们总是将较大的值添加到较小的值中，则该序列的行为类似于斐波那契增长。 从值开始直到`10^9`，超过之前需要的操作次数`n`只有几十个。 这意味着如果我们总是做出正确的贪婪选择，简单的模拟就已经足够快了。 

有一些边缘情况值得仔细检查。 

认为`a = 1`,`b = 1`,`n = 1`。 答案是`1`， 不是`0`，因为目标是严格大于`n`。 最初两个值相等`n`，所以仍然需要一次操作。 

认为`a = 1`,`b = 2`,`n = 3`。 经过一次操作我们可以达到`(3,2)`或者`(1,3)`，但两个值都不超过`3`。 需要进行第二次手术。 正确答案是`2`。 当值变得等于时停止的粗心实现`n`会产生错误的结果。 

认为`a = 5`,`b = 4`,`n = 100`。 选择不当的更新会增加操作次数。 例如，反复将较小的值添加到较大的值中，其增长速度比最优策略慢。 最低限度的答案要求每一步都尽可能地增加。 

## 方法

 暴力的观点是将每个操作视为二元选择。 来自一个州`(a, b)`我们可能会搬到`(a + b, b)`或者`(a, a + b)`。 由于我们想要最少的操作数，因此我们可以想象对所有可达状态进行广度优先搜索。 

这种方法是正确的，因为 BFS 探索的是增加操作数的状态。 问题在于州的数量。 即使经过适度数量的步骤，分支因子 2 也会创造指数级的多种可能性。 这样的搜索是完全不切实际的。 

关键的观察是，在任何时刻，如果我们想超过`n`我们应该尽快将较大的数字添加到较小的数字中。 

认为`a ≤ b`。 

如果我们执行`a += b`，新值变为`a + b`。 

如果我们执行`b += a`，新值变为`b + a`，但较小的值保持不变。 

第一个选择转变`(a, b)`进入`(a + b, b)`，而第二个将其转换为`(a, a + b)`。 

任一操作后较大的数是相同的，即`a + b`。 不同的是，第一个选择也会增加较小的值。 较大的较小值只能帮助将来的操作，因为以后的每次加法都使用这两个数字。 保持较小的值尽可能大不会有坏处，而且通常会有所帮助。 

这导致了一个简单的贪心过程：

 继续将较大的数字与较小的数字相加，直到其中一个超过`n`。 

由于值像斐波那契数一样增长，因此迭代次数很少。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最优贪心模拟 | O(k) | O(1) | O(1) | 已接受 |

 这里`k`是执行的操作数，对于给定的约束最多为 50 左右。 

## 算法演练

 1. 将操作计数器初始化为零。 
2. 虽然两者`a`和`b`至多是`n`，继续执行操作。 
3. 比较两个值。 
4. 如果`a < b`， 履行`a += b`。 
5. 否则执行`b += a`。 

这总是会增加较小的值，从而为未来的增长产生最大可能的对。 
6. 增加操作计数器。 
7. 当任一值大于`n`，停止并输出计数器。 

### 为什么它有效

 每一步，让`x`是较小的值并且`y`为较大值。 

接下来的两个可能的状态是`(x + y, y)`和`(x, x + y)`。 

两者都创造了相同的新最大值，`x + y`。 差额就是剩余价值。 保持为`y`总是至少和保持它一样好`x`， 因为`y ≥ x`。 

因此，在一次操作之后，更新较小的值会产生一种状态，该状态的两个数字都至少与替代状态中的相应数字一样大。 由于未来的操作仅涉及这些值的相加，因此从组件方面更大的状态开始不能需要更多的操作来超过`n`。 

因此，总是存在一个最优解，在每一步更新较小的值，这正是算法所做的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        a, b, n = map(int, input().split())
        
        ops = 0
        
        while max(a, b) <= n:
            if a < b:
                a += b
            else:
                b += a
            ops += 1
        
        print(ops)

solve()
```当两个数字还不够大时，循环将继续。 使用`max(a, b) <= n`相当于说两个值都不超过`n`。 

贪心步总是更新较小的值。 这是该解决方案的中心思想。 每次更新后我们都会增加操作计数器。 

Python 整数具有任意精度，因此即使值可能暂时变得大于`10^9`。 

一个常见的错误是当值等于时停止`n`。 该问题要求一个值_严格大于_`n`，所以条件必须是`<= n`循环内。

 ## 边缘情况

 考虑：```
1
1 1 1
```最初两个值都不大于`1`。 算法进入循环，执行`b += a`，生产`(1, 2)`，然后停止。 输出是`1`。 这证实了等于`n`不满足目标。 

考虑：```
1
1 2 3
```执行过程是：`(1,2) -> (3,2) -> (3,5)`第一次操作后的最大值恰好是`3`，因此循环继续。 第二次操作后最大值变为`5`，这超过了`3`。 输出是`2`。 这正确地处理了严格的不平等。 

考虑：```
1
10 10 10
```执行过程是：`(10,10) -> (10,20)`一次操作就足够了，因为`20 > 10`。 检查的实现`>= n`在执行任何移动之前会错误地返回`0`。 

考虑：```
1
5 4 100
```贪心策略不断更新较小的值并达到上面的值`100`在七次行动中。 任何有时更新较大值的策略都会使较小的数字不必要地变小，并且无法更快完成。 这证明了贪心选择的正确性。
