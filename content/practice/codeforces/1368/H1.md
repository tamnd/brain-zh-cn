[CF 1368H1 - 面包板容量（简易版）](https://codeforces.com/problemset/problem/1368/H1)

 **评分：** 3300
 **标签：** dp、流量、贪婪
 **求解时间：** 2m
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们有一个矩形面包板`n`行和`m`内部节点的列。 沿着板的四个侧面有端口。 左右两侧都有贡献`n`每个端口，而顶部和底部侧贡献`m`每个端口。 

每个端口的颜色为红色或蓝色。 我们可以使用板内绘制的电线连接端口。 每根电线必须恰好连接一个红色端口和一个蓝色端口。 一个端口最多可以参与一个连接。 

几何限制令人惊讶地宽松。 导线可以水平和垂直移动，可以在节点处转弯，可以在节点处相交，并且仅禁止正长度的重叠段。 

任务是计算红蓝连接的最大可能数量。 

从约束中首先要注意的是`n`和`m`每个都能达到`10^5`。 端口总数为$$2n + 2m \le 4 \cdot 10^5.$$任何涉及网格本身的算法都会立即受到怀疑，因为从概念上讲，该板可能包含最多`10^10`节点。 我们无法对板内的单元、路径或图形顶点进行建模。 解决方案必须仅取决于边界端口。 

一个常见的错误是假设几何形状会产生复杂的布线约束。 事实上，简单版本几乎完全崩溃为计数问题。 

考虑这个例子：```
1 1 0
R
R
R
R
```所有四个端口均为红色。 根本没有蓝色端口，因此无法形成连接。 

答案是：```
0
```仅计算总端口数并除以二的粗心解决方案将错误地返回`2`。 

现在考虑：```
1 1 0
R
B
R
B
```有两个红色和两个蓝色端口。 

答案是：```
2
```尽管该板仅包含一个内部节点，但仍然可以实现两个独立的连接。 一种可以使用左侧和右侧端口，另一种可以使用顶部和底部端口。 任何基于节点容量的推理都会低估答案。 

另一个微妙的情况是：```
2 1 0
RR
RB
B
B
```红色端口 = 3，蓝色端口 = 3。 

答案是：```
3
```正确的容量等于较小的颜色数。 任何为特定连接保留特定行或列的尝试都会产生实际上并不存在的人为限制。 

真正的挑战是证明几何形状永远不会将可实现的匹配降低到低于此颜色计数界限。 

## 方法

 强力的观点是将每个红色端口和每个蓝色端口视为连接的可能端点，并询问是否可以在板内同时路由所有选定的对。 

这自然地暗示了几何图形结构、平面路由参数，甚至是巨大网格上的流动。 董事会可能包含最多`10^10`内部节点，因此任何显式表示都是没有希望的。 即使压缩流模型也太大了。 

关键的观察结果是，面包板比最初看起来要灵活得多。 

假设我们要将任何选定的红色端口连接到任何选定的蓝色端口。 从第一个端口开始，我们可以进入棋盘，移动到一些未使用的水平走廊，穿越，如果需要的话垂直移动，最后到达第二个端口。 由于允许电线在节点处相交，并且仅禁止重叠的线段，因此行和列的大量集合就像一个具有丰富自由度的路由网络。 

这个问题的编辑解决方案依赖于更强有力的声明：

 可以实现红、蓝边界端口任意匹配。 

一旦这是真的，几何图形就会完全消失。 唯一剩下的限制是每种颜色的可用端口数量。 

如果有`R`红色端口和`B`蓝色端口，每个连接消耗每种颜色的一个端口。 任何溶液都不能包含超过`min(R, B)`连接。 

上面的路由定理表明这个界限总是可以实现的。 

因此答案很简单：$$\min(R, B)$$在哪里`R + B = 2n + 2m`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力路由/流| 至少 O(nm) 并且通常更糟 | O(纳米) | 太慢了 |
 | 最佳计数 | O(n + m) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取四个边界字符串。 
2. 计算所有四个侧面有多少个端口呈红色。 
3. 计算四个侧面有多少个端口呈蓝色。 
4. 每个有效连接恰好消耗一个红色端口和一个蓝色端口，因此任何解决方案都不能包含超过`min(red, blue)`连接。 
5. 面包板布线结构足够丰富，可以实现任何红蓝配对，因此这个上限是可以实现的。 
6. 输出`min(red, blue)`。 

### 为什么它有效

 每个连接都使用一个红色端点和一个蓝色端点。 这立即给出了上限`min(red, blue)`。 

重要的部分表明电路板的几何形状没有施加额外的限制。 由于导线可以共享节点，因此仅禁止边缘重叠，并且网格包含任意多个独立的水平和垂直线段，因此可以同时路由任何红蓝对的集合。 硬版本通过流程解释将其形式化； 在简单版本中，所得容量恰好等于颜色平衡端点对的最大可能数量。 

由于上限总是可以达到的，因此容量精确地为`min(red, blue)`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())

    left = input().strip()
    right = input().strip()
    top = input().strip()
    bottom = input().strip()

    red = (
        left.count('R') +
        right.count('R') +
        top.count('R') +
        bottom.count('R')
    )

    total = 2 * n + 2 * m
    blue = total - red

    print(min(red, blue))

if __name__ == "__main__":
    solve()
```实现直接遵循数学特征。 

前四个字符串包含边界上的所有端口。 计算红色端口比单独计算两种颜色稍微简单一些。 一旦知道端口总数，就可以得到蓝色计数：`total - red`。 

的价值`q`被读取是因为它出现在输入格式中，即使在此版本中它始终为零并且对答案没有影响。 

不需要大型数据结构。 该解决方案对每个字符只处理一次。

 ## 边缘情况

 考虑：```
1 1 0
R
R
R
R
```算法算数`red = 4`,`blue = 0`，并返回`0`。 每个连接都需要一个蓝色端点，因此不可能建立连接。 

考虑：```
1 1 0
R
B
R
B
```算法算数`red = 2`,`blue = 2`，并返回`2`。 尽管电路板很小，但两个红色端口都可以与两个蓝色端口配对。 答案仅取决于颜色计数。 

考虑：```
2 2 0
RR
RB
BB
BB
```该算法计算`red = 3`,`blue = 5`，给出答案`3`。 可以形成三个红蓝对，其余两个蓝色端口保持未使用。 任何解决方案都不能超过三个，因为只存在三个红色端口。 

考虑一种极其不平衡的配置，其中只有一个端口是红色的，而所有其他端口都是蓝色的。 算法返回`1`。 每个有效的解决方案都必须消耗唯一的红色端口，使一个连接成为绝对最大连接。 电路板的几何形状无法增加该限制。
