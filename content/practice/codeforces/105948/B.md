 ## 解决方案
 ## 问题理解

 我们正在模拟简化节奏游戏的评分系统，其中只有两种音符类型保持相关：TAP 和 BREAK。 每个音符都会被评判为多个演奏类别之一，每个类别对最终分数的贡献不同。 

输入给我们两个直方图。 第一个描述了每个判断类型收到了多少个 TAP 音符，第二个描述了每个判断类型收到了多少个 BREAK 音符。 根据这些计数，我们必须重建最终得分的两个组成部分。 

最终得分由两部分组成。 第一个是基本分数，它取决于 TAP 和 BREAK 音符，并进行缩放，使其最大值为 100。第二个是奖励分数，仅取决于 BREAK 音符，最多贡献 1 分。 最终答案是这两个值的总和，截断至小数点后四位。 

核心困难在于，单个音符的贡献不仅取决于其类型和判断，还取决于全局量，例如 TAP 和 BREAK 音符的总数，因为比例因子使用其分母中的音符总数。 这意味着如果不首先计算全局总数，我们就无法独立处理每个类别。 

约束足够小，对 13 个输入整数进行一次线性传递就足够了。 除了仔细的浮点计算之外，不需要进行优化。 

一个微妙的失败案例是由精度和顺序引起的。 由于需要截断小数点后四位，因此绝不能隐式进行四舍五入。 例如，像 99.99999 这样的值必须变为 99.9999，而不是 100.0000。 另一个陷阱是忘记了 BREAK 音符对基本分数和奖励分数都有贡献，但系数不同。 

## 方法

 幼稚的解释可能会尝试计算每个音符类型的贡献，而不仔细分离缩放因子。 人们可能会尝试直接将每个类别计数乘以其系数并独立除法，但这会破坏，因为 TAP 和 BREAK 贡献共享从 TAP 和 BREAK 音符总数得出的归一化常数。 

正确的暴力方法会单独模拟每个音符。 我们可以将所有 TAP 和 BREAK 计数扩展为显式列表，并一一计算贡献。 这是正确的，但没有必要。 在最坏的情况下，最多有 1000 个 TAP 条目和 800 个 BREAK 条目，因此这仍然很小，但在概念上很笨拙，并且在应用缩放时很容易错误地实现。 

关键的观察结果是，所有贡献与每个类别的注释数量呈线性关系。 我们只需要一次 TAP 和 BREAK 音符的总数，然后对每个类别应用固定乘数。 这将问题简化为恒定的算术量。 

我们计算 TAP 总计 T 和 BREAK 总计 B。然后我们预先计算 x = 100 / (T + 5B) 和 y = 1 / B。每个 TAP 类别贡献其计数乘以系数乘以 x。 每个 BREAK 类别对基本分数的贡献相似，并分别对奖励分数做出贡献。 

从按音符推理到按类别聚合的转变使解决方案变得立竿见影。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力扩张| O(T + B) | O(T + B) | 已接受但没有必要 |
 | 聚合公式| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 ### 步骤

1. 读取所有 TAP 类别计数并计算总 TAP 音符 T. 读取所有 BREAK 类别计数并计算总 BREAK 音符 B. 这些总数定义两个评分组件的标准化。 
2. 计算基本缩放分母 T + 5B，因为 BREAK 音符在基本分数归一化中的权重是原来的五倍。 
3、定义TAP基础系数为1、1、1、0.8、0.5，分别对应5个TAP判断类别。 
4.将BREAK基础系数定义为5、5、5、4、3、2.5、2、0，对应于基础分数贡献的八个BREAK判断类别。 
5. 计算 x = 100 / (T + 5B)。 这会将加权计数转换为百分比基本分数。 
6. 通过将每个 TAP 计数乘以其系数乘以 x，以及每个 BREAK 计数乘以其系数乘以 x 来累加基本分数。 
7. 计算奖励缩放 y = 1 / B。 
8. 仅使用 BREAK 判断计算奖励分数：C.Perfect 贡献 1，Perfect1 贡献 0.75，Perfect2 贡献 0.5，Great 类别贡献 0.4，而其他类别贡献 0。 
9. 将奖金总和乘以 y，将其标准化为 [0, 1] 中的值。 
10. 将基本分数和奖励分数相加，然后将结果截断至小数点后四位。 

### 为什么它有效

 系统中的每个贡献与音符数量呈线性关系，类别之间的唯一耦合来自共享的归一化常数 T + 5B 和 B。一旦这些总数固定，每个类别都会独立贡献。 该算法通过将归一化与累积分开来保留精确的权重，确保类别之间的交互不会丢失或重复计算。 最后的截断确保符合评分格式，而不会在中间计算中引入浮点舍入误差。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

a = list(map(int, input().split()))
b = list(map(int, input().split()))

T = sum(a)
B = sum(b)

# base score coefficients
tap_coef = [1.0, 1.0, 1.0, 0.8, 0.5]
break_base_coef = [5.0, 5.0, 5.0, 4.0, 3.0, 2.5, 2.0, 0.0]

# bonus coefficients
break_bonus_coef = [1.0, 0.75, 0.5, 0.4, 0.4, 0.4, 0.0, 0.0]

x = 100.0 / (T + 5 * B)
y = 1.0 / B

base = 0.0
for i in range(5):
    base += a[i] * tap_coef[i] * x

for i in range(8):
    base += b[i] * break_base_coef[i] * x

bonus = 0.0
for i in range(8):
    bonus += b[i] * break_bonus_coef[i]

bonus *= y

ans = base + bonus

# truncate to 4 decimals
ans = int(ans * 10000) / 10000.0

print(f"{ans:.4f}")
```该方案在分离归一化因子后直接对评分公式进行编码。 TAP和BREAK数组使用固定系数表独立处理，这可以防止将判断类型映射到乘法器时出现错误。 

截断步骤是在缩放 10000 后显式使用整数下限完成的，这避免了浮点舍入问题，否则可能会使值略高于正确的截止值。

 ## 边缘情况

 一种关键的边缘情况是，除了未命中之外没有 BREAK 音符，这仍然使 B 为正值，但对奖金和基础的贡献为零。 该公式仍然正确运行，因为 y = 1 / B 仍然定义良好，并且 MISS 的所有系数均为零，不会产生意外的通货膨胀。 

另一种边缘情况是 T 较小且 B 较大时。 由于 BREAK 音符的分母加权为 5，因此基础分数显着下降。 该算法自然地处理这个问题，因为缩放因子 x 已经编码了这种不平衡。 

最后一个微妙的情况是截断。 如果计算值非常接近下一个可表示的 4 位十进制数，则在未显式截断的情况下，浮点算术可能会错误地舍入。 无论浮点表示如何，整数缩放步骤都确保确定性下限。
