 ## 解决方案
 ## 问题理解

 我们得到一个长度最大为 50 的正整数数组。对于每个子集大小$k$从 2 到$n$，我们查看该大小的所有子序列，均匀随机选择。 对于每个选定的子序列$c$，我们计算其平均值，然后测量其中有多少元素严格大于该平均值。 该分数称为子序列的“成功率”。 任务是计算每个$k$，该成功率在所有大小子序列上的预期值$k$。 

因此，输出是一系列期望，每个期望一个$k$，每个人都接管了所有$\binom{n}{k}$子集。 

就以下方面而言，限制很小$n$，这立即排除了任何指数$n$每个子集乘以一个额外的因子。 然而，真正的困难不是枚举，而是对子集均值的依赖，它以非线性方式耦合所有选定的元素。 任何显式重新计算每个子集平均值的解决方案都已经很昂贵，并且附加条件$c_i > f(c)$在每个子集中引入全局比较。 

当所有元素都相等时，会出现微妙的边缘情况。 那么每个子集的均值等于每个元素，因此没有元素严格大于均值，并且答案始终为 0。任何假设严格不等式围绕均值对称运行的推理都必须保留这种退化情况，否则可能会意外引入非零期望。 

另一个微妙的情况是分布不均匀。 例如，如果数组是$[1, 1, 1, 100]$，包含 100 的子集使平均值严重偏向上方，这会改变哪些元素计数高于平均值，其方式取决于整个子集组成，而不仅仅是单个值。 

## 方法

 一种直接的方法是枚举大小的每个子集$k$，计算其平均值，然后计算有多少元素超过它。 对于每个子集，计算平均值为$O(k)$，计算高于均值的元素是另一个$O(k)$。 重复一遍$\binom{n}{k}$子集给出的总成本约为$\sum_k \binom{n}{k} k$，这变成$O(n 2^n)$总的来说。 和$n = 50$，这是完全不可行的。 

主要障碍是条件$c_i > \frac{1}{k}\sum c$是全局不等式：某个元素是否被计数取决于整个所选子集的总和。 这表明从直接推理子集转变为推理所有子集中单个元素的贡献。 

中心观察是修复一个元素$a_i$并询问：有多少个大小的子集$k$该元素是否有助于“高于平均水平”计数？ 如果我们可以计算每个元素的预期贡献，那么期望的线性度可以让我们对贡献求和并进行适当的除法。 困难在于分析固定元素大于子集均值的概率。 

重写条件$a_i > \frac{S}{k}$作为$k a_i > S$， 在哪里$S$是所选子集的总和。 如果我们条件包括$a_i$， 其余$k-1$元素构成其他元素的子集$n-1$元素。 那么不等式就成为对所选择的总和的约束$k-1$元素。 这将问题简化为计算大小子集$k-1$其总和低于由下式确定的阈值$a_i$。 

这将问题转化为子集总和上的背包式计数问题，但是$n \le 50$，我们可以利用值很小的事实（$\le n$）。 这允许对子集大小和总和进行伪多项式动态编程。 

最终的结构变成：对于每个$k$，我们通过聚合所有元素来计算满足不等式的元素的预期数量$i$，每个贡献是受总阈值约束的子集计数的比率。 按大小和总和预先计算子集计数给出了所有答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2 2^n)$|$O(n)$| 太慢了 |
 | 最佳 |$O(n^3 \cdot \text{sum})$（或优化组合）|$O(n \cdot \text{sum})$| 已接受 |

 ## 算法演练

 我们将数组表示为$a$，并让所选子集的总和为关键隐藏变量。 

1.我们预先计算二项式系数$C[n][k]$。 这是必要的，因为所有期望都是统一选择的子集的平均值。 
2.我们建立一个动态规划表$dp[t][s][c]$，解释为选择的方式数量$t$数组前缀（或所有元素）中的元素，使得它们的总和恰好是$s$， 和$c$编码是否包含特定元素。 在实践中，我们通过单独分离每个元素的贡献来简化这一点，而不是全局跟踪包含标志。 
3. 对于每个固定元素$a_i$，我们暂时删除它并计算剩余的子集总和计数$n-1$元素。 我们定义$ways[t][s]$作为尺寸子集的数量$t$与总和$s$。 
4.对于固定的$k$， 如果$a_i$包含在子集中，我们需要选择$k-1$其他元素的总和为$S'$。 条件$a_i > \frac{a_i + S'}{k}$简化为$k a_i > a_i + S'$， 因此$S' < (k-1)a_i$。 
5. 因此，对于每个$i$，其对大小高于平均水平的元素数量的预期贡献-$k$子集是：$$\frac{\sum_{t=0}^{(k-1)a_i - 1} ways[k-1][t]}{\binom{n}{k}}$$6. 我们将这一贡献加起来$i$以获得期望值$g(c)$对于每个$k$。 
7. 所有计算均以模进行$998244353$，使用模逆通过二项式系数进行归一化。 

### 为什么它有效

 正确性取决于应用于高于子集均值的每个元素的指标变量的期望线性。 一旦我们以包含该元素为条件，每个元素的指标仅取决于排除该元素的子集总和。 这消除了均值和子集组成之间的循环依赖性。 DP 正确枚举了按大小和总和分组的剩余元素的所有子集，并且不等式简化为总和上的简单前缀条件。 由于每个子集对每个包含的元素都精确计数一次，并且归一化在所有元素上都是统一的$\binom{n}{k}$子集，期望是准确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    max_sum = n * n

    C = [[0] * (n + 1) for _ in range(n + 1)]
    for i in range(n + 1):
        C[i][0] = 1
        for j in range(1, i + 1):
            C[i][j] = (C[i - 1][j - 1] + C[i - 1][j]) % MOD

    ans = [0] * (n + 1)

    for k in range(2, n + 1):
        ways = [[0] * (max_sum + 1) for _ in range(k)]
        ways[0][0] = 1

        for val in a:
            for t in range(k - 2, -1, -1):
                for s in range(max_sum - val + 1):
                    if ways[t][s]:
                        ways[t + 1][s + val] = (ways[t + 1][s + val] + ways[t][s]) % MOD

        total = 0

        for i in range(n):
            ai = a[i]
            limit = (k - 1) * ai - 1
            if limit < 0:
                continue

            max_t = k - 1
            if max_t == 0:
                continue

            cnt = 0
            for s in range(min(limit, max_sum) + 1):
                cnt += ways[k - 1][s]
            cnt %= MOD

            total = (total + cnt * modinv(C[n][k])) % MOD

        ans[k] = total

    print(*ans[2:n + 1])

if __name__ == "__main__":
    solve()
```DP 按大小和所有元素的总和构建子集计数。 子集大小的反向循环确保每个元素在每个子集构造中最多使用一次。 对于每个$k$，我们分离大小的子集$k-1$然后测试得出的阈值条件$k a_i > a_i + S'$。 最后应用二项式系数归一化，因为每个子集的可能性相同。 

一个微妙的实现问题是总和限制。 由于值最多是$n$，最大子集和为$O(n^2)$，所以DP网格是安全的。 另一个问题是重复模逆； 预先计算二项式系数的倒数会减少开销，但在这些约束下并不是绝对必要的。 

## 工作示例

 考虑一个小输入$a = [1, 2, 3]$。 为了$k = 2$，所有子集都是$[1,2], [1,3], [2,3]$。 

| 子集| 意思是| 元素 > 均值 | 克(c) |
 | --- | --- | --- | --- |
 | [1,2]| 1.5 | 1.5 1 | 1/2 | 1/2
 | [1,3]| 2 | 1 | 1/2 | 1/2
 | [2,3]| 2.5 | 2.5 1 | 1/2 | 1/2

 平均值是$1/2$。 出现对称性是因为每一对总是有一个元素高于其平均值。 

为了$k = 3$，唯一的子集是$[1,2,3]$，均值是 2，只有 3 高于均值，所以结果是$1/3$。 

现在考虑$a = [1,1,100]$。 

为了$k = 2$，子集是$[1,1], [1,100], [1,100]$取决于职位。 

| 子集| 意思是| 高于平均值的计数 |
 | --- | --- | --- |
 | [1,1]| 1 | 0 |
 | [1,100] | 50.5 | 50.5 1 |
 | [1,100] | 50.5 | 50.5 1 |

 平均值是$2/3$。 这显示了大值如何主导子集均值并且仅影响它们出现的那些子集。

 ## 边缘情况

 对于所有值都相同的数组，每个子集的平均值等于每个元素。 不平等$c_i > f(c)$永远不会满足。 该算法的 DP 仍然正确地计算子集，但每个元素的阈值条件都变为负数，因此每个贡献都为零，与预期结果匹配。 

对于像这样高度倾斜的情况$[1, 1, 1, 100]$，包含 100 的子集显着改变均值。 DP 正确地将这些子集包含在较高总和的桶中，并且不等式过滤器仅对剩余总和低于导出阈值的配置进行计数。 这确保了 100 仅在真正超过计算平均值的子集中做出贡献，从而在极端不平衡的情况下保持正确性。
