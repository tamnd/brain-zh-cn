 ## 解决方案
 ## 问题理解

 我们给出了一个尺寸的网格$n \times m$将多个芯片放置在电池上。 通过沿四个方向之一应用单个全局移动，每个芯片都可以与所有其他芯片同时移动：上、下、左或右。 移动会将每个芯片朝该方向移动一个单元，除非芯片已经位于边界上并且将移出边界，在这种情况下，该芯片只是保持在原位，而其他芯片仍在移动。 

对于每个芯片，我们还给出了一个目标单元，该芯片在整个全局移动序列中必须至少访问一次。 这些芯片的移动方式没有什么区别，但每个芯片都有自己所需的“检查点”单元，该特定芯片的轨迹必须访问该单元。 

输出最多是一个序列$2nm$移动，或声明不存在这样的序列。 

关键的困难在于所有芯片共享相同的移动序列，因此我们不会独立地对每个芯片进行布线。 相反，我们正在尝试设计整个网格的单一路径，以保证每个芯片在某个时间通过其指定的目标。 

限制很小：$n, m, k \le 200$。 这立即表明解决方案涉及$O(nm)$或者$O(nmk)$推理是可行的，并且任何二次方$k$可能还是可以接受的。 然而，对所有可能的移动序列进行简单的模拟是指数级的并且是不可能的。 

一个微妙的一点是边界行为很重要。 卡在边缘的芯片可能“落后于”全局运动，这对于构建有效重新定位芯片而无需单独单独控制芯片的路径至关重要。 

当人们假设每个芯片都可以独立路由到其目标时，就会出现一种常见的失败情况。 这是错误的，因为单个动作会同时影响所有筹码。 另一个错误是试图贪婪地按顺序将每个筹码移动到其目标； 早期的芯片可能已经满足了他们的要求，但如果不仔细构建，后来的举措可能会意外地使进度假设失效。 

## 方法

 一个蛮力的想法是尝试构建移动序列并模拟是否所有筹码最终都通过其目标单元。 甚至将自己限制在长度序列上$2nm$，每步分支因子为 4，因此搜索空间为$4^{2nm}$，这是完全不可行的。 

即使是更结构化的蛮力，例如对所有芯片位置的状态进行 BFS，也是不可能的，因为每个状态都编码$k$位置，给出大小的状态空间$(nm)^k$，又太大了。 

关键的观察是我们不需要单独控制芯片。 网格的全局扫描可以以受控方式“覆盖”每一行或每一列，确保每个芯片都被迫穿过电路板的大部分。 

一个自然的想法是确保网格的每个单元在某个时刻成为“活动边界”，以便任何尚未到达其目标的芯片将被迫经历其目标与其轨迹对齐的配置。 解决此类问题的标准建设性技巧是逐行、逐列重复扫描网格。 通过蛇形遍历模式，我们可以保证全局坐标系以结构化的方式访问每个单元，并且芯片由于与墙壁的相对位移而被迫通过所有相关位置。 

中心思想是，以受控模式完全遍历网格边界就足够了：通过在扫过网格的方向上重复推动芯片，我们可以确保每个芯片最终到达其可到达区域中的每个单元，并且由于网格是有限的，我们可以保证在范围内所有所需的目标访问$O(nm)$移动。 

更精确的建设性策略是使用交替的左右扫描和向下过渡，以类似哈密顿路径的方式遍历整个网格。 这确保了每个细胞都以系统的方式受到全球运动的“触及”，而边界剪切则确保了芯片的滞后性，从而使覆盖范围变得普遍。

 ## 算法演练

 我们构建了一个系统性地横扫棋盘的确定性运动序列。 

1. 从概念上从左上角开始，对第一行执行完全水平扫描。 我们向右移动$m-1$次。 这确保了每个芯片都被水平地推过行，同时边界条件防止溢出。 
2. 向下移动一次以过渡到下一行。 这种向下移动会将所有切屑向下移动，除非它们已经位于底部，在这种情况下，它们保持固定，从而产生向下行的受控压缩。 
3.应用从右向左扫第二行$m-1$向左移动。 这种交替方向至关重要，因为它可以防止冗余振荡并确保线性时间内的完全覆盖。 
4. 对所有行重复此模式：在每行上交替水平方向并在行之间插入向下移动。 
5. 完成所有行后，如果需要，可以选择执行最终清理扫描以确保最后一行对齐，尽管构造的路径已经保证了完全覆盖。 

直觉是，每行都在两个水平方向上完全遍历交替层，并且垂直移动确保跨所有行的过渡。 每个芯片都被迫在网格结构上经历完整的投影，这意味着它必须在扫描过程中的某个点穿过其行中的每个单元。 

### 为什么它有效

 不变的是，完成每行扫描后，每个芯片要么已经访问了该行中的所有单元，要么已经以受控方式垂直移动，以确保其参与未来的行扫描。 由于水平扫描覆盖每行中的每个列位置，而垂直移动可确保遍历所有行，因此保证每个芯片在遍历过程中的某个点与其目标单元格重合。 最多移动次数有限$2nm$，由每行段两次水平移动加上每行边界一次垂直过渡得出。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    for _ in range(k):
        input()
    for _ in range(k):
        input()

    res = []

    for i in range(n):
        if i % 2 == 0:
            res.append("R" * (m - 1))
        else:
            res.append("L" * (m - 1))
        if i != n - 1:
            res.append("D")

    ans = "".join(res)
    if len(ans) > 2 * n * m:
        print(-1)
    else:
        print(len(ans))
        print(ans)

if __name__ == "__main__":
    solve()
```由于构造不依赖于各个芯片位置，因此代码首先读取并丢弃芯片信息。 移动序列是逐行构建的，交替水平方向。 每行贡献精确$m-1$移动，并且除了最后一行之后之外，每个转换都会贡献一次向下移动。 

一个微妙的点是长度检查。 施工最多保证$n(m-1) + (n-1) \le 2nm$，因此该检查是多余的，但出于安全考虑而包含在内。 

交替方向至关重要。 如果没有它，边界附近的芯片将不会经历对称覆盖，并且隐式遍历论证将会失败。

 ## 边缘情况

 1×1 网格是最简单的边界。 该算法会生成一个空序列，因为不需要移动。 每个芯片都已经占据了它唯一可能的单元，所以这个要求很容易满足。 

对于 1×m 网格，该算法仅产生正确的移动。 由于没有向下转换，因此序列长度恰好为$m-1$。 芯片不能离开行，并且全扫描保证移动框架访问每一列。 

对于 n×1 网格，构造退化为仅向下移动。 每个芯片都被迫通过所有行，因为水平移动是无关的，并且垂直扫描覆盖了所有需要的位置。 

这些案例证实了该结构在简并维度上正确倒塌，而没有打破运动界限。
