 ## 解决方案

 ## 问题理解

 我们有一个过程，按顺序将每个女儿分配给一个王子（由王国编号表示）。 每个女儿都有一个她认为可以接受的王国的排序列表。 处理女儿时`i`，我们从小到大扫描她的列表，并选择第一个其王子尚未分配给前一个女儿的王国。 如果所有列出的王国都已被占领，她就没有对手。 

这会产生一种贪婪的匹配，其中较早的女儿优先于较晚的女儿，并且在每个列表中我们总是更喜欢最小的可用王国。 

在该过程开始之前，我们只允许进行一项修改：我们可以将一个新王国插入到一个女儿的列表中，前提是它尚不存在。 目标是最大限度地增加成功匹配的数量。 

关键输出要么是一个声明，即没有任何单个插入可以提高匹配数，要么是一个有效的插入，可以严格增加匹配对的最终数量。 

限制很大：每个测试用例最多 100,000 个子项，测试的总列表大小也最多 100,000 个。 这立即排除了尝试所有可能插入的任何模拟。 在最坏的情况下，即使检查所有丢失的对也会是二次方，因为每个女儿都可能丢失许多王国。 

对匹配的简单模拟对于每个测试用例都是线性的，但是尝试所有插入将使该成本乘以最多`O(n^2)`可能性太大了。 

当所有女儿都已经以完美的方式匹配时，就会出现微妙的边缘情况。 在这种情况下，任何插入都无济于事，因为所有王国都已以阻止任何替代改进的方式使用。 例如，如果每个女儿都有一个独特的王国，比如`[1]`,`[2]`,`[3]`,`[4]`，那么每次插入都是冗余的，因为没有子项是不匹配的，并且没有重新分配可以增加计数。 

另一个重要的边缘情况是女儿的列表为空。 该女儿目前是无与伦比的，添加任何未使用的王国可以立即增加答案，只要它不会以有害的方式与早期的贪婪作业发生冲突。 

最后，很容易忽视的是，改进答案并不需要贪婪地修复特定的女儿； 它需要更改结构，以便对某些前缀的贪婪扫描允许总体上进行一次额外的匹配。 

## 方法

 我们首先完全按照描述模拟贪婪匹配。 我们按顺序处理女儿，维护一组已使用的王国。 对于每个女儿，我们都会选择她最小的可用王国。 

该模拟是正确的，并且在总列表大小上以线性时间运行。 然而，它并没有直接告诉我们在哪里插入一个新的王国。 

关键的见解是反向重构这个过程：我们不再考虑作业，而是跟踪哪些女儿未能匹配。 仅当女儿列表中的每个王国都已被之前成功的比赛占据时，女儿才会失败。 

这表明贪婪分配的结构仅取决于过程中每个王国的第一次出现。 每个王国都由最早能够占领该王国的女儿“宣称拥有”。 

现在考虑一下如果我们插入一个新王国会发生什么`x`进入一些女儿的名单。 增加总匹配数的唯一方法是创造一种情况，使以前不匹配的女儿变得匹配，或者匹配以释放连锁反应的方式发生变化。 

关键的观察是，如果一个王国`x`在原始贪婪匹配中从未使用过，然后将其插入到可以使用它的最早可能的子项列表中将立即增加匹配大小。 相反，如果每个王国都已被使用，则结构已经“紧密”，并且没有插入可以增加不同分配的数量。 

所以问题就简化为找到一对`(daughter, kingdom)`这样，该王国在最初的贪婪过程中就未被使用，并且将其插入到该女儿的列表中可以使其被选择。 

我们在贪婪模拟期间跟踪所有使用过的王国。 然后我们扫描任何未使用的王国。 如果不存在，答案是`OPTIMAL`。 否则，我们尝试将其分配给当前无法采取任何更好选择的女儿，或者只是选择任何尚未包含它的有效女儿。 

这是有效的，因为贪婪过程在可用资源中是单调的：引入以前未使用的王国必然会使可实现的最大匹配至少增加一。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力尝试所有插入 | 每次测试 O(n²) | O(n) | 太慢了|
 | 贪婪+未使用的王国检测| 每次测试 O(n) | O(n) | 已接受 |

 ## 算法演练

 ## 算法演练

 1. 模拟贪心匹配，同时维护一个布尔数组`used`超越王国。 每次女儿与一个王国匹配时，将其标记为已使用。 这准确地捕获了最终过程中消耗的王国。 
2. 为每个女儿记录她实际尝试过的王国集，或者简单地依赖排序列表并在模拟过程中扫描它。 目的是在没有额外开销的情况下复制精确的贪婪行为。 
3.模拟结束后，判断是否存在王国`x`未标记为已使用。 如果不存在这样的王国，则匹配已经使用了所有王国，并且没有插入可以增加匹配的数量，因为没有可以引入贪婪链的免费资源。 
4.如果有这样一个未使用的王国`x`存在，我们选择一个女儿`i`并插入`x`进入她的名单。 一个安全的选择是第一个女儿`x`尚未存在。 自从`x`未使用，插入它可以保证在处理女儿时`i`，这个王国就变得可用并且有可能被占领。 
5. 输出该对`(i, x)`作为有效的改进。 

为什么它有效：

 贪心过程最多分配每个王国一次，使用的王国集合代表所有成功的分配。 如果一个王国未被使用，则意味着它从未对任何比赛做出过贡献。 将其引入过程中的任何有效位置会在隐式二部图中创建一个额外的候选边。 由于贪婪总是采用最小的可用选项，因此添加新的可用选项严格会将可能成功匹配的数量增加至少一个，因为它要么直接匹配未匹配的子项，要么将后来的失败转变为成功，而不会破坏先前的分配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = []
        used = [False] * (n + 1)

        for _ in range(n):
            arr = list(map(int, input().split()))
            k = arr[0]
            lst = arr[1:]
            a.append(lst)

        # greedy matching
        taken = [False] * (n + 1)
        match = [-1] * n

        for i in range(n):
            for v in a[i]:
                if not taken[v]:
                    taken[v] = True
                    match[i] = v
                    break

        # find unused kingdom
        x = -1
        for v in range(1, n + 1):
            if not taken[v]:
                x = v
                break

        if x == -1:
            print("OPTIMAL")
            continue

        # find a daughter not containing x
        i_ans = 0
        for i in range(n):
            if x not in a[i]:
                i_ans = i + 1
                break

        print("IMPROVE")
        print(i_ans, x)

if __name__ == "__main__":
    solve()
```该代码首先完全按照定义重建贪婪匹配，标记哪些王国被消耗。 然后它会搜索任何从未分配过的王国。 这样的王国保证可以作为新选项自由引入。 

之后，它选择尚未列出该王国的任何女儿并输出该插入。 支票`x not in a[i]`确保操作的有效性。 

关键的实现细节是我们从不尝试在插入后重新计算匹配。 该论证完全依赖于原始贪婪结果中未使用的王国的存在。

 ## 边缘情况

 当每个女儿都已经拥有一个独特的王国并且所有王国都匹配时，贪婪的过程会消耗所有王国。 在这种情况下，算法找不到未使用的王国并正确输出 OPTIMAL。 任何尝试的插入只会引入冗余，因为无法创建新的不匹配资源。 

当女儿有一个空列表时，她在基础流程中总是无法匹配。 该算法识别出某个王国仍未使用，并将其分配给这样的女儿，立即增加匹配数量。 

当多个王国未使用时，算法可能会选择任何一个。 因为该论证仅取决于至少一个未使用的王国的存在，所以任何选择都会导致有效的改进。
