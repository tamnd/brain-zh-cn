 ## 解决方案

 ## 问题理解

 我们从概念上写下每个整数$0$到$10^n - 1$，但我们强制每个数字都具有精确的$n$通过用前导零填充来填充数字。 这会创建一个巨大的数字字符串多集，每个数字字符串的长度$n$，涵盖了所有可能的数字组合$000\ldots0$到$999\ldots9$。 

在任何固定数字内，我们可以将其数字序列拆分为相等连续数字的最大分段。 每个这样的段称为一个块，其长度就是值改变之前连续出现的相同数字的数量。 

任务不是直接检查个人号码。 相反，我们必须算一下$10^n$数字，到底有多少块长度$i$出现，对于每一个$i$从$1$到$n$。 答案必须以模计算$998244353$。 

约束条件$n \le 2 \cdot 10^5$立即排除任何迭代所有数字甚至模拟每个数字的数字转换的方法。 任何尝试显式构造或迭代的方法$10^n$字符串是不可能的。 即使在线性时间内对每个数字进行推理也意味着$O(n \cdot 10^n)$，这是一个天文数字。 

一个天真的替代方案是考虑生成随机数字序列和计数运行，但即使这样也隐藏了相同的指数爆炸。 问题的结构表明我们必须按位置或按块进行推理，聚合贡献而不枚举数字。 

例如，当所有数字都相等时，会出现微妙的边缘情况$000\ldots0$。 在这种情况下，只有一个长度块$n$，并且没有更小的块。 在这种情况下，任何假设每个数字有多个块的不正确的分解策略都会导致计数过高。 另一个微妙的情况是交替数字，例如$010101\ldots$，其中每个块的长度为 1，最大化块的数量但最小化它们的大小。 这些极端情况暗示块长度的分布仅取决于游程结构，而不取决于特定的数字值。 

## 方法

 蛮力方法会生成每一个$n$-数字字符串并显式扫描它以计算游程长度。 每个字符串需要$O(n)$工作，并且有$10^n$字符串，给予$O(n \cdot 10^n)$，即使对于$n = 20$。 

关键的观察结果是，除了相邻位置之间的相等或不相等之外，数字值是不相关的。 重要的是数字之间的转换发生在哪里。 每个位置要么继续前一个块，要么开始一个新块。 这减少了从枚举字符串到分析相邻位置之间的相等模式的问题。 

我们将问题重新解释为计算通过在相邻位置之间选择断点形成的片段的贡献。 一块长度$i$对应的最大间隔为$i$连续的相等数字，由不同数字或数字边界界定。 我们不是构造字符串，而是计算一个长度块有多少种方式$i$可以通过固定其边界并确保数字的一致性来出现。 

关键的简化是，我们可以根据转换独立地处理每个位置，并使用组合学来计算有多少配置在给定位置产生给定大小的块。 对所有位置求和得出最终结果。 这导致了关于位置和游程长度的 DP 公式，其中转换仅取决于我们是继续还是开始一个新块。

 ## 算法演练

 我们逐个位置处理数字字符串结构，但我们不跟踪实际数字，而是跟踪当前块的长度以及导致该状态的配置数量。 

1. 我们定义一个动态编程状态，在其中累积给定长度的块可以在给定位置结束的方式的计数。 这避免了完全区分数字值，因为所有数字的行为都是对称的。 
2. 对于每个位置，我们考虑是继续前一个块还是开始一个新块。 继续将当前块长度增加 1，而开始新块会将长度重置为 1。 
3.当一个块的长度$i$结束于位置$p$，我们记录对答案长度的贡献$i$。 这是因为该块在该端点处最大。 
4. 我们跨位置传播转换，维护产生当前游程长度的配置计数。 数字选择的数量仅在开始一个新块时才重要，其中我们有 9 个与前一个数字不同的选择，但对称性允许我们将这种效果聚合为乘法因子。 
5. 我们迭代从 1 到$n$，更新 DP 状态并将每个块长度的贡献累积到答案数组中。 

核心思想是每个块都由其起始位置和结束位置唯一标识，并且与该块兼容的数字分配数量仅取决于边界是否匹配或不同，而不取决于实际数字。 

### 为什么它有效

 该算法依赖于以下不变量：在每个位置，DP 状态表示与将前缀固定划分为最大相等块一致的数字序列的数量，仅根据最后一个块的长度进行分类。 由于数字身份是可互换的，并且只有等式约束才重要，因此每个有效的数字分配恰好对应于 DP 中的一个转换路径。 每块长度$i$当它在右边界闭合时，只计算一次，确保不会多算或少算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    
    # dp[len] = number of ways current run has length len
    dp = [0] * (n + 1)
    dp[0] = 1
    
    # ans[i] = number of blocks of length i
    ans = [0] * (n + 1)
    
    for pos in range(1, n + 1):
        new_dp = [0] * (n + 1)
        
        for length in range(0, pos):
            val = dp[length]
            if val == 0:
                continue
            
            # continue same digit -> extend block
            if length + 1 <= n:
                new_dp[length + 1] = (new_dp[length + 1] + val) % MOD
            
            # start new block -> previous block ends at length
            if length > 0:
                ans[length] = (ans[length] + val) % MOD
            
            # starting new block from scratch (position boundary)
            new_dp[1] = (new_dp[1] + val * 9) % MOD
    
        dp = new_dp
    
    # last position contributions
    for length in range(1, n + 1):
        ans[length] = (ans[length] + dp[length]) % MOD
    
    print(*ans[1:])

if __name__ == "__main__":
    solve()
```该代码在扫描位置时在当前游程长度上维护 DP。 这`dp[length]`值表示有多少个部分构造产生当前大小的后缀块`length`。 当扩展一个块时，我们会增加它的长度。 当一个区块结束时，我们将其贡献添加到`ans`。 因素`9`当开始一个新块时出现，因为可以选择与前一个不同的任何数字。 

最后的扫描添加到达数字末尾的剩余开放块。 

主要的微妙之处是确保每个块在终止时（无论是在其扩展位置还是在字符串末尾）都被准确计数。

 ## 边缘情况

 对于$n = 1$，每个数字恰好由一个长度为 1 的块组成。这样的数字有 10 个，因此答案是单个值 10，与直接枚举匹配。 

对于像 000…0 这样的完全统一的字符串，只有一个长度块$n$。 DP 确保计算一次，因为没有任何转换会中断运行。 

对于交替数字模式，每个块的长度为 1，算法将最大贡献累积到$ans[1]$通过重复重启，匹配单长度块的预期主导地位。
