 ## 解决方案
 ## 问题理解

 我们有两个相同长度的整数数组。 第一个数组以非常有限的值开始，每个位置要么是负一，零，要么是正一。 第二个数组可以包含任意整数，其大小可能非常大。 任务是决定是否可以使用重复修改元素的特定操作将第一个数组转换为第二个数组。 

允许的操作选择两个索引，第一个索引严格在第二个索引之前，然后将较早位置的值添加到较晚位置。 重要的是，源位置不会改变，并且该操作可以重复任意多次，包括重复使用同一对。 

关键的限制是影响力只能从左向右流动。 较早的元素可以影响较晚的元素，但反之则不然。 这将创建一个跨阵列的定向传播系统。 

所有测试用例的输入大小总共允许多达十万个元素。 这立即排除了指数对之间操作的任何二次模拟，因为即使是模拟每个位置的重复更新的单一简单尝试也会远远超出时间限制。 

理解重复操作实际上能实现什么效果会出现一个微妙的困难。 由于可以多次选择同一对，因此可以将单个非零值重复应用于以后的位置，这意味着该操作不是一次性传输，而是可重复使用的影响源。 

往往会打破天真的推理的边缘情况包括所需的增加较早出现但唯一的积极来源较晚出现的情况，例如像这样的数组`[0, 1]`试图成为`[1, 0]`。 这是不可能的，因为正值太右，无法帮助第一个位置。 另一个失败案例是假设总金额很重要。 例如，匹配总和并不能保证可行性，因为操作是定向的并且不允许向后重新排列质量。 

## 方法

 强力解释将直接模拟操作。 我们会重复扫描所有对`(i, j)`并在任何看起来有用的时候应用更新，直到不再发生任何更改或数组与目标匹配。 这种方法原则上是正确的，因为它精确地模拟了允许的操作，但每个操作都可以无限地应用，并且存在 O(n^2) 对，导致无限或极大数量的迭代。 即使将我们限制在一个合理的上限，n 仍然无法扩展到 100000。 

关键的观察结果是操作的结构极其粗糙。 初始数组中的每个位置要么是积极影响、消极影响或中立的永久来源。 值为 1 意味着我们可以重复地将 1 添加到任何后面的位置。 值减一意味着我们可以从后面的任何位置重复减一。 零什么也不做。 

这将整个过程变成了可达性条件而不是模拟问题。 对于目标数组中的每个位置，我们只需要知道在该位置之前的前缀中是否已经遇到了至少一个正源和至少一个负源。 如果我们需要相对于其初始状态增加一个值，我们需要访问左前缀中的正源。 如果我们需要减少它，我们需要在左前缀中有一个负源。 一旦存在这样的源，它就可以无限次地重复使用，因此我们永远不需要多个源。 

这将问题简化为单个线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n²) 或更糟 | O(n) | 太慢了|
 | 前缀来源追踪 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例，从左到右扫描，同时跟踪到目前为止在原始数组中是否看到了正测试用例或负测试用例。 

1. 初始化两个布尔标志，一个表示前缀中是否出现了正数，另一个表示是否出现了负数。 
2. 从左到右迭代每个索引。 在每个位置，首先使用原始数组中的值更新标志。 如果当前元素为 1，则正标志变为 true。 如果它是负一，则负标志变为真。 零不会改变任何事情。 
3. 比较该位置两个数组的当前值。 如果目标值大于原始值，那么我们需要使用加一的方式增加这个位置，这要求前缀中已经存在正源。 如果不存在这样的源，那么转变是不可能的。 
4. 如果目标值小于原始值，则需要使用减一操作来减少目标值，这要求前缀中存在负源。 如果不存在，则转变是不可能的。 
5. 如果任何索引都不违反任何一个条件，则可以进行转换。 

关键的一点是，我们永远不需要跟踪源被使用了多少次，只需要跟踪它是否存在于可达前缀中。 

### 为什么它有效

 操作结构使原始数组中的每个非零条目成为所有后续位置的单位增量或减量的可重用生成器。 一旦某个索引 i 出现值 1，每个大于 i 的位置 j 都可以通过重复操作从 i 接收任意多个增量。 这同样适用于作为无限递减源的负一。 因为源永远不会被消耗，只会被引入到前缀中，所以唯一有意义的状态是每一侧是否至少存在一个源。 

这将所有可行性问题减少到前缀存在检查，这些检查在整个扫描过程中保持一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        has_pos = False
        has_neg = False
        ok = True
        
        for i in range(n):
            if a[i] == 1:
                has_pos = True
            elif a[i] == -1:
                has_neg = True
            
            if b[i] > a[i]:
                if not has_pos:
                    ok = False
                    break
            elif b[i] < a[i]:
                if not has_neg:
                    ok = False
                    break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```该实现遵循算法中描述的扫描。 在检查每个索引的可行性之前更新标志，因为当前位置本身可以作为以后索引的源（如果它不为零）。 

一个常见的微妙错误是在检查条件后更新标志。 这将错误地阻止位置 i 处的值在允许时被用于满足位置 i 本身的约束。

 ## 边缘情况

 常见的边缘情况是所需的操作取决于数组中稍后出现的源。 例如，如果第一个位置需要减少，但第一个负值仅出现在其后，则即使存在全局负值，转换也会失败。 该算法正确地拒绝了这一点，因为前缀标志在评估时仍然为假。 

另一个微妙的情况是初始数组的所有元素都为零。 由于零不能生成任何更改，因此与初始数组不同的任何目标数组都会立即失败，这是通过在整个扫描过程中缺少两个标志来正确捕获的。 

第三种情况是仅存在一种类型的源时。 如果数组仅包含 1，则无论未来的结构如何，任何所需的减少都是不可能的，并且当出现没有前缀否定的否定要求时，扫描会立即检测到这一点。
