 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，并要求计算该序列中有多少连续段在特定意义上是“稳健的”。 如果某个段的每个非空连续子段的总和不为零，则该段被视为有效。 

同样，我们正在搜索所有子数组，并仅保留那些没有内部间隔完全抵消为零的子数组。 候选段内的单个零和子数组足以取消其资格。 

输入大小高达 200,000 个元素，这会立即排除任何显式检查所有子数组的解决方案。 一种简单的方法是检查 O(n²) 个子数组，并检查每个子数组的内部零和结构，将其推向 O(n³) 或最多 O(n² log n)，这远远超出了 2 秒的可行限制。 

关键的困难在于，条件不仅仅涉及整个子数组，还涉及其所有内部子段。 这引入了一个不直接位于端点本地的嵌套约束。 

一些边缘情况值得尽早隔离。 

完全无零的前缀和结构并不能保证正确性。 例如，在`[1, -1, 2]`，整个数组有非零和，但它是无效的，因为`[1, -1]`总和为零。 天真的“仅检查总和”方法在这里失败了。 

另一个微妙的情况是重叠取消。 在`[1, 2, -1, -2]`，无论是前缀还是后缀单独看起来都不危险，但内部结构会创建多个零和区间。 

真正的挑战是检测子数组是否包含任何在其内部重复的前缀和对，因为这正是零和子数组存在的时候。 

## 方法

 暴力法很简单。 对于每个子数组`[l, r]`，我们可以计算其中的前缀和并检查任何两个前缀和是否一致。 如果确实如此，则意味着某些内部段的总和为零。 如果不是，则子数组有效。 这需要扫描所有 O(n²) 子数组，每次检查的成本为 O(n)，产生 O(n³)。 即使使用前缀散列来更快地检测重复项，我们仍然会得到 O(n²) 个子数组和每个子数组边界管理的 O(n) 工作量，这仍然太慢。 

关键的观察是反转条件。 当且仅当存在一对时子数组无效`(i, j)`在其中使得 prefixSum[i] 等于 prefixSum[j]。 这意味着每个无效子数组都“被迫”包含一些重复的前缀和对。 

我们不检查子数组的内部重复，而是跟踪前缀和全局重复的位置。 对于每个位置，我们可以维护每个前缀和的最后一次出现。 如果我们在索引处`r`，然后从以下位置开始的任何子数组`l <= lastSeen[prefixSum[r]] + 1`将包含重复的前缀和，从而以可预测的方式变得无效。 

这将问题转化为对子数组进行计数，以避免因先前出现的前缀和而引入的冲突。 我们可以处理右端点并维护最小的有效左边界。 

这个问题变成了一个经典的“具有约束传播的双指针”：当我们扩展右边界时，只要我们检测到前缀和重复会违反窗口内的条件，我们就会向前移动左边界。

 ## 算法演练

 我们使用前缀和将子数组和编码为差异。 

1. 计算前缀和`pref`， 在哪里`pref[i]`是第一个的总和`i`元素。 这允许任何子数组和表示为`pref[r] - pref[l-1]`。 
2.维护字典`last`将每个前缀和值映射到其最近的索引。 这跟踪最后一次看到每个累积总和的位置。 
3. 维护指针`l`表示以当前位置结束的子数组的最小有效起始索引。 最初，`l = 1`。 
4. 迭代`r`从 1 到 n。 对于每个位置：

 1.如果`pref[r]`之前已经在索引中看到过`p`，然后是开始于或之前的任何子数组`p`将在结束于的窗口内包含重复的前缀和`r`。 因此，更新`l = max(l, p + 1)`。 
2. 更新`last[pref[r]] = r`。 
5. 对于每个`r`，所有以`r`并从`l`到`r`是有效的。 添加`(r - l + 1)`到答案。 

### 为什么它有效

 当两个相等的前缀和出现在零和子数组中时，零和子数组就存在。 跟踪最后出现的情况可确保我们始终了解影响当前端点的最严格的重复。 左指针`l`始终停留在任何会在当前窗口内创建禁止的重复前缀和的位置之外。 这保证了每个计数子数组的所有前缀和都是不同的，这相当于没有零和内部段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pref = 0
    last = {0: 0}
    l = 1
    ans = 0

    for r in range(1, n + 1):
        pref += a[r - 1]

        if pref in last:
            l = max(l, last[pref] + 1)

        last[pref] = r

        ans += (r - l + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案使用前缀和将子数组和转换为差异，然后使用哈希映射来跟踪每个前缀和最后出现的位置。 左指针确保我们永远不会计算包含重复前缀和的段。 关键的实现细节是前缀和的索引是从 1 开始的，而数组是从 0 开始的，这在计算窗口大小时保持算术干净。 

更新内容`l = max(l, last[pref] + 1)`至关重要。 它可以防止窗口包含较早出现的相同前缀和，否则会在段内引入零和子数组。

 ## 边缘情况

 单元素数组始终有效，因为不存在内部子数组。 算法初始化`last = {0: 0}`并计数`(r - l + 1) = 1`，符合预期结果。 

具有重复前缀和的数组，例如`[1, -1, 1, -1]`触发左边界的频繁重置。 每次前缀和`0`重新出现时，较早的片段将被排除。 实现正确更新`l`跳过无效的起始位置，确保不会错误地计算包含完全取消的子数组。 

大型均匀数组，例如`[1, 1, 1, ..., 1]`永远不会产生前缀冲突，所以`l`保持固定为 1。每个子数组都是有效的，答案变为`n(n+1)/2`，算法通过自然累积`(r - l + 1)`在每一步。
