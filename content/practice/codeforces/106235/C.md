 ## 解决方案
 ## 问题理解

 我们正在模拟一家咖啡馆的座位系统，其中人和桌子都按重要性排序。 关键的想法是，每个人到达的时间间隔是固定的，在此期间他们占据一张桌子，并且桌子不能容纳重叠的时间间隔。 

必须为每个黑手党分配一个在其整个时间段内空闲的编号最低的桌子。 如果之前分配的坐在该桌子上的人没有与他们有重叠的时间间隔，则该桌子被认为对该人来说是免费的，即使接触端点也算作重叠。 

所以我们按照从 1 到 n 的顺序处理黑手党。 对于每个人，我们尝试重用从表 1 开始的现有桌子，并分配第一个与已经坐在那里的人在时间上不冲突的桌子。 

输出只是按输入顺序分配给每个人的表。 

这些约束总共允许最多 250,000 个间隔。 对每个表之前分配的所有间隔进行简单检查会太慢，因为每个分配可能会扫描许多过去的间隔，从而在最坏的情况下导致二次行为。 

微妙的边缘情况来自边界接触。 如果一个间隔在时间 t 结束，另一个间隔在时间 t 开始，它们仍然被认为是冲突的，因此它们不能共享一张表。 例如，区间 [1, 2] 和 [2, 3] 必须进入不同的表。 

另一个极端情况是许多间隔嵌套或相同。 如果许多黑手党共享相同的时间范围，则即使他们的时间范围相同，每个黑手党也必须获得不同的桌子。 

## 方法

 最简单的方法是为每个表维护指定间隔的完整列表，并检查新间隔是否与其中任何一个重叠。 每次检查都会扫描已放置在该表中的所有间隔。 在最坏的情况下，如果所有间隔严重重叠，我们最终会检查每个新黑手党之前的几乎所有分配，从而导致大约 O(n²) 操作。 

该过程的结构表明具有全局排序约束的贪婪分配。 我们总是想要最小的可用桌子，一旦桌子被分配给黑手党，我们只需要知道它何时再次空闲。 这减少了维护每个表的最早可用时间的问题。 

当处理间隔为 [a_i, b_i] 的黑手党时，如果最后分配的间隔严格在 a_i 之前结束，则表有效。 因为端点算作重叠，所以不允许相等，所以我们要求last_end < a_i。 

这就把问题变成了重复选择last_end小于a_i的最小索引表。 为了有效地做到这一点，我们维护一个以每个表的下一个可用时间为键的优先级结构。 每次我们分配一个表时，我们都会将其下一个空闲时间更新为 b_i。 

最小堆非常适合：它存储对（next_free_time，table_id）。 堆总是给出最早空闲的表。 但是，由于我们还需要空闲表中最小的索引有效表，因此我们必须小心。 关键的观察是，如果我们将所有表保留在堆中，我们可以暂时提取那些尚未释放的表，并在检查可行性后重新插入它们。 由于每个表在每次分配时都会被推送和弹出一次，因此每次操作的总复杂度保持对数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 基于堆的贪婪 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

1. 初始化一个包含所有表的优先级队列，每个表的 next_free_time = 0 及其索引。 这表示最初所有表都立即可用。 
2. 按顺序从 1 到 n 处理黑手党，因为较早的黑手党在分配和约束方面具有优先权。 
3、对于当前区间为[a_i,b_i]的mafioso，在其next_free_time不严格小于a_i的情况下，重复提取堆顶。 这些表暂时不可用，因为它们在 a_i 或之后仍被占用。 
4. 第一个提取的满足next_free_time < a_i的表是最早可用的表中索引最小的可行表。 将此表分配给当前的黑手党。 
5. 将该表的 next_free_time 更新为 b_i，因为它现在已被占用，直到时间 b_i（含）。 
6. 将所有临时删除的表原封不动地推回堆中，然后将更新的表也推回堆中。 
7. 记录作业并继续。 

步骤 3 安全的原因是，任何违反时间限制的表都不能用于当前的黑手党，但未来的黑手党可能仍需要它，因此必须将其恢复。 

### 为什么它有效

 在每一步中，堆中的每个表都正确地表示在处理所有先前的黑手党之后它变得空闲的最早时间。 堆不变量保证当我们选择一个表时，我们会在最后分配的时间间隔在当前开始时间之前结束的所有表中选择最小的可用索引。 由于我们总是分配第一个可行表并立即更新其可用性，因此未来的分配不会追溯性地产生冲突。 处理的顺序确保所有约束仅来自已分配的间隔，因此可行性仅取决于每个表的last_end。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        intervals = [tuple(map(int, input().split())) for _ in range(n)]

        # heap: (next_free_time, table_id)
        heap = [(0, i) for i in range(1, n + 1)]
        heapq.heapify(heap)

        ans = [0] * n

        for i, (a, b) in enumerate(intervals):
            blocked = []

            # find first available table
            while heap and heap[0][0] >= a:
                blocked.append(heapq.heappop(heap))

            # now heap[0] must be valid
            free_time, table_id = heapq.heappop(heap)

            ans[i] = table_id

            # push back blocked tables
            for item in blocked:
                heapq.heappush(heap, item)

            # update chosen table
            heapq.heappush(heap, (b, table_id))

        print(*ans)

if __name__ == "__main__":
    solve()
```该实现直接反映了算法。 堆存储每个表空闲的时间。 弹出阻塞表的循环是必要的，因为堆是按最早的空闲时间排序的，而不是按当前间隔开始的可行性排序，因此我们暂时删除在时间 a_i 时仍占用的所有表。 

这里的一个常见错误是忘记平等也算作重叠。 这就是为什么条件是`heap[0][0] >= a`而不是`>`。 

另一个微妙之处是，我们总是在移至下一个黑手党之前推回所有临时删除的表，否则我们将永久失去有效的候选人。

 ## 边缘情况

 当所有间隔都相同时，每个黑手党必须收到一个不同的表。 堆会重复阻塞所有现有表，直到到达新表，并且每次分配都会更新一个不同的条目，从而产生严格递增的表索引序列。 

当间隔恰好在端点处接触时，例如 [1,2] 和 [2,3]，第二个间隔不能重用同一个表，因为 next_free_time 等于开始时间，而不是小于开始时间。 该算法通过检查正确地阻止该表`>= a_i`，确保选择一个新表。 

当间隔不相交并且在时间上向前排序时，堆会快速找到同一张表而不会阻塞，因为它的 next_free_time 总是小于下一个开始时间。 这表明只要限制允许，重用就会最大化。
