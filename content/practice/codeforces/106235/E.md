 ## 解决方案
 ## 问题理解

 我们得到一个加权图，其中沿边移动是有成本的，并且我们关心从固定起始节点到固定目标节点的路径。 在从起点到目标的所有可能的步行中，有一个可能的总成本最小，即通常的最短路径。 

任务不是输出最短路径。 相反，我们必须找到最便宜的路径，其总成本严格大于最短可能成本。 换句话说，如果我们想象按升序对所有有效的起始到目标路径成本进行排序，我们希望第一个值大于最小值。 

输入通过顶点和加权边描述图。 除非另有说明，每个边缘都允许在两个方向上行进。 输出是表示此“最佳严格非最佳”路径成本的单个数字，如果不存在此类路径，则输出是失败值。 

关键的结构性困难在于“非最短”是一个全局约束。 路径无效并不是因为边的局部属性，而是因为它的总权重与全局最优值完全匹配。 

从复杂性的角度来看，图的大小足够大，不可能枚举所有简单的路径。 即使具有 10^5 条边的图也会使不同行走的数量呈指数增长，因此任何解决方案都必须依赖于最短路径结构而不是路径枚举。 这会立即排除路径上的 DFS 或任何组合搜索。 

一些边缘情况很重要。 

从起点到目标只有一条路径的图表非常重要。 在这种情况下，每条有效路径都有相同的成本，因此不存在严格意义上更大的替代路径，答案应该是不可能的。 

另一个微妙的情况是存在多个最短路径。 例如，如果两条不相交的路线都达到相同的最小成本，则下一条候选路径可能仅在探索成本增加最小量的绕道后出现。 像“删除最短路径中使用的边”这样的天真的想法可能会失败，因为不同的最短路径可能只共享一些边，而删除单个边集可能会错误地消除所有有效的替代方案。 

## 方法

 暴力方法会尝试枚举从源到目标的所有可能路径，计算其成本，并选择大于最短路径成本的最小成本。 这在概念上是正确的，因为它显式地检查每个候选者，但在计算上是不可能的。 在有循环的图中，行走的次数是无限的，甚至限制为简单的路径也会导致可能性数量的阶乘增长。 

关键的观察是我们实际上不需要枚举路径。 我们只需要从源到目标的两个最小的不同距离。 最短的是标准 Dijkstra。 第二个距离可以通过扩展 Dijkstra 的思想来计算，即每个节点保持多个已知距离。 

我们不是存储每个节点的单个最佳距离，而是存储最佳和次佳距离。 当放松边缘时，新的候选距离可以改善这两个值中的任何一个。 这是有效的，因为到节点的任何路径都可以通过其总成本来表征，并且对于最终答案，我们只关心保留到达目的地的最小的两个不同成本。 

暴力破解会失败，因为它探索整个路径级别的结构，而最优解决方案将所有路径压缩为仅包含两个相关状态的每个节点排名。

 ## 算法演练

 我们为每个节点维护两个值：到目前为止看到的最小距离和严格大于第一个距离的第二小距离。

然后，我们使用状态优先级队列运行类似 Dijkstra 的过程，其中每个状态都是一对（距离，节点）。 

1. 将最佳和次佳数组的所有距离初始化为无穷大。 将 best[source] 设置为 0 并将 (0, source) 推入优先级队列。 
2. 弹出与优先级队列距离最小的状态。 该状态代表下一个最有希望的部分路径。 
3. 对于通过权重为 w 的边可到达的每个邻居，计算候选距离 nd = dist + w。 
4. 如果 nd 小于该邻居的最佳已知距离，则将旧的最佳状态移至次佳状态，更新最佳状态，并将新的最佳状态推入队列。 
5. 否则，如果 nd 严格介于 best 和 secondary-best 之间，则更新 secondary-best 并将其推入队列。 
6. 继续，直到队列为空。 
7. 答案是目标节点处的第二最佳距离。 

这样做的原因是，每次我们从优先级队列中最终确定一个状态时，我们都会以成本非递减的顺序处理路径。 这确保了当我们分配最佳值和第二最佳值时，它们会以正确的排序顺序被发现，而不会丢失任何中间候选值。 

节点上的第二最佳值保证是严格大于最佳成本的最小成本，因为任何更便宜的替代方案都会更早地通过队列排序进行处理。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    
    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, w))
        g[v].append((u, w))

    # best and second best distances
    dist1 = [INF] * n
    dist2 = [INF] * n

    pq = []
    dist1[0] = 0
    heapq.heappush(pq, (0, 0))

    while pq:
        d, u = heapq.heappop(pq)

        if d > dist2[u]:
            continue

        for v, w in g[u]:
            nd = d + w

            if nd < dist1[v]:
                dist2[v] = dist1[v]
                dist1[v] = nd
                heapq.heappush(pq, (nd, v))

            elif dist1[v] < nd < dist2[v]:
                dist2[v] = nd
                heapq.heappush(pq, (nd, v))

    ans = dist2[n - 1]
    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```该图被存储为邻接列表，因为我们在松弛期间重复扫描邻居。 两个数组`dist1`和`dist2`实现每个节点的路径成本排序。 

一个微妙的实现细节是条件`d > dist2[u]`，它会修剪已经比已知的第二最佳到达节点的方式更糟糕的状态。 如果没有这个，优先级队列可能会变得不必要的大。 

另一个重要的细节是严格的不平等`dist1[v] < nd < dist2[v]`。 允许平等会将相同成本的不同路径折叠到同一类别中，这将打破最短路径和严格非最短路径之间的区别。 

## 工作示例

 ### 示例 1

 考虑一个具有节点 1 到 4 和边的图：

 | 步骤| 节点| 距离 | dist1 更新 | dist2 更新 |
 | ---| ---| ---| ---| ---|
 | 开始| 1 | 0 | 距离1[1]=0 | - |
 | 放松 | 2 | 2 | 距离1[2]=2 | - |
 | 放松 | 3 | 2 | 距离1[3]=2 | - |
 | 替代路径 | 3 | 5 | - | 距离2[3]=5 |
 | 达到目标 | 4 | 3 | 距离1[4]=3 | - |
 | 绕行路线 | 4 | 6 | - | 距离2[4]=6 |

 这里，到节点 4 的最短路径是 3，下一个最佳不同路径是 6，因此答案是 6。该表显示仅当发现严格更大的替代路由时才出现第二最佳值。 

### 示例 2

 所有路径共享相同成本的图表：

 | 步骤| 节点| 距离 | 距离 1 | 距离2 |
 | ---| ---| ---| ---| ---|
 | 开始| 1 | 0 | 0 | 信息 |
 | 路径A | n | 10 | 10 10 | 10 信息 |
 | 路径 B | n | 10 | 10 10 | 10 信息 |

 不会出现严格更大的路径，因此第二好的路径仍然是无穷大，答案是 -1。 这证实了该算法正确区分“没有替代方案”和“存在替代方案”。

 ## 边缘情况

 仅存在一条简单路径的图表显示了朴素推理的失败模式。 算法正确地保持了`dist2[target]`为无穷大，因为没有替代路线以严格更大的形式进入队列。 

具有多个最短路径的图测试第二最佳跟踪是否忽略等成本路由。 条件`dist1[v] < nd`确保等长路径不会覆盖或污染次佳状态。 

具有循环的图可以生成无限多个游走，但优先级队列排序确保仅保留每个节点的两个最小相关距离。 这可以防止循环引发的爆炸，同时如果在所有非最短选项中是最佳路径，仍然允许较长的绕道成为第二最佳路径。
