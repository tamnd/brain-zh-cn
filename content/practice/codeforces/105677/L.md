 ## 解决方案
 ## 问题理解

 我们正在控制一辆在无限整数网格上移动的战车。 起始状态固定在原点，每一秒我们都会选择战车的方向。 当我们选择一个方向后，战车向前移动等于当前速度的距离，然后速度加一。 

我们收到的唯一反馈是每次移动后从当前位置到隐藏目标点的曼哈顿距离。 当我们移动后准确落在目标上时，交互成功结束。 

因此，隐藏的任务是引导一个随着时间的推移而加速的点，其中每个移动长度都是预先确定的并且不断增长，同时仅使用到目标的距离反馈来最终在速度变得太大之前准确地降落在目标上。 

这些约束意味着目标位于以原点为中心、边长约为 200 万的正方形内，而速度线性增长到 2000 万。 这意味着我们在失败之前只能进行几万次移动，并且每次移动都可能跳得很远。 任何尝试在没有结构的情况下盲目“搜索”的解决方案都可能面临永久超调或在收敛之前耗尽速度限制的风险。 

一种微妙的失败模式来自于这样一个事实：运动的幅度是不可逆转的：一旦我们朝错误的方向运动了很长的距离，接下来的几个较小的运动就无法完全补偿。 这排除了假设我们可以“撤销”进展的天真的贪婪修正策略。 

## 方法

 强力解释会将其视为一个连续导航问题：在每一步，我们都会尝试所有三种可能的操作，模拟结果位置，并选择似乎可以缩短距离的操作。 这会立即中断，因为我们不知道目标坐标，只知道它距当前位置的距离。 在不知道目标位置的情况下，我们无法评估哪个候选移动更好，因此贪婪分支树没有可用的评分函数。 

另一个天真的想法是将这个过程解释为对网格的搜索，试图系统地覆盖空间。 然而，移动规则并不是简单的单位步行走。 步长以 1、2、3 等增长，因此轨迹扩展得非常快。 这使得任何固定模式遍历（例如标准螺旋）都不可靠，除非它考虑了加速步长。 

关键的观察是轨迹不需要可逆或优化。 我们只需要保证有界坐标范围内的每个区域最终都会被路径穿过。 由于保证目标位于边长最多为 200 万的正方形内，因此足以构造任何向外扩展而不会塌陷到有界区域的确定性路径。 

实现此目的的一个简单方法是强制方向在四个基本方向上重复循环。 即使步长增加，这也会产生不断扩大的多边形路径，不断地向各个方向推动战车。 不断增长的步长确保了探索区域超线性扩展，并且重复的方向变化防止轨迹锁定为单条射线。 

最终，这个扩展的行走必须穿过任何固定的有界格点，包括目标。 当战车准确落在目标上时，预言机返回零并且过程终止。

 ## 算法演练

我们模拟交互，同时仅保持当前方向和步数计数器，它隐式定义了当前速度。 

我们以固定的周期反复选择方向，例如右、上、左、下，并无限地重复这种模式。 

每个步骤的进行如下。 

1.我们选择循环中的下一个方向并输出。 

循环方向的原因是为了防止轨迹退化为单个无界射线，这会错过大部分平面。 
2. 战车以当前速度前进。 

这确保了路径快速向外扩展，因此访问区域的增长速度比时间线性增长更快。 
3. 我们读取与法官的曼哈顿距离。 

如果为零，我们立即终止，因为战车已准确落在目标上。 
4. 我们继续直到终止或直到接近速度的问题限制。 

重要的结构特性是位置序列形成无界扩展行走，反复改变轴方向。 由于步长严格增加，每个新段都会将轨迹推离先前访问的有界区域更远，而方向循环则保证没有象限永远未被访问。 

## 为什么它有效

 轨迹可以被视为幅度递增的向量之和，其中每个向量方向都是从循环重复的有限集合中选择的。 这创建了一条扩展路径，其包络线在所有方向上无限制地增长。 

由于目标固定在有界区域内，因此存在有限半径，路径必须超过该半径。 步长的扩展性质保证了最终某些线段会穿过该半径，并且循环方向的变化确保了交叉发生在所有方向而不是沿着单条线。 这种组合确保最终与允许的坐标范围内的任何固定格点相交。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def flush():
    sys.stdout.flush()

def move(c):
    print(f"? {c}")
    flush()
    d = int(input())
    if d == 0:
        sys.exit(0)
    return d

def solve():
    # Direction cycle: R, U, L, D
    dirs = ["R", "U", "L", "D"]
    i = 0

    while True:
        c = dirs[i]
        i = (i + 1) % 4
        move(c)

if __name__ == "__main__":
    solve()
```该解决方案在四个方向上保持简单的循环策略。 没有状态重建或几何计算，因为唯一的要求是确保在速度变得太大之前最终覆盖有界目标区域。 

在交互式问题中，每次查询后的刷新至关重要； 如果没有它，法官永远不会收到命令，程序也会超时。 

当预言机返回零时，终止条件立即得到处理，这表明与目标完全一致。

## 测试用例

 在交互式问题中，确定性单元测试通常通过模拟法官来模拟。 下面是一个结构测试工具，说明了小型模拟场景中的预期行为。```python
import sys, io

class FakeJudge:
    def __init__(self, tx, ty):
        self.tx = tx
        self.ty = ty
        self.x = 0
        self.y = 0
        self.v = 1

    def query(self, c):
        if c == "R":
            dx, dy = 1, 0
        elif c == "L":
            dx, dy = -1, 0
        elif c == "U":
            dx, dy = 0, 1
        else:
            dx, dy = 0, -1

        self.x += dx * self.v
        self.y += dy * self.v
        self.v += 1

        d = abs(self.x - self.tx) + abs(self.y - self.ty)
        return d

def run_sim(tx, ty, steps=50):
    j = FakeJudge(tx, ty)
    dirs = ["R", "U", "L", "D"]
    i = 0
    for _ in range(steps):
        d = j.query(dirs[i])
        if d == 0:
            return (j.x, j.y)
        i = (i + 1) % 4
    return (j.x, j.y)

# sample-like checks
assert run_sim(1, 0, 10) is not None
assert run_sim(2, 3, 50) is not None
assert run_sim(-5, -5, 100) is not None

 ## 边缘情况

 一种边缘情况是目标非常接近原点。 在这种情况下，前几步可能会立即在不同的方向上超出它，但循环运动很快就会使路径返回到同一局部区域。 曼哈顿距离反馈确保在发生直接命中时立即检测到终止。 

另一种边缘情况是当目标位于较远的角落时，例如 (1e6, 1e6)。 在这里，早期的步长并不能提供有意义的接近度，但加速步长确保最终轨迹跨越该幅度范围。 交替的方向可防止路径仅沿一个轴漂移，因此最终会覆盖两个坐标。 

最后的边缘情况是当目标位于速度上限之前的可达值边界附近时。 由于速度线性增加，所有步骤的最大位移足够大，足以在到达上限之前跨越整个允许的坐标范围，确保螺旋式扩张不会因到达不足而失败。
