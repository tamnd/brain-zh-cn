 ## 解决方案
 ## 问题理解

 我们得到一排塔，每个塔从左到右位于整数坐标处，每个位置都分配有高度。 所有高度都不同，因此有一座独特的最高塔。 

对于除了最高的塔之外的每座塔，我们都会寻找严格高于它的最近的塔。 “最近”是以索引距离来衡量的，因此向左或向右移动一步需要花费一个单位。 塔会贡献与较近的较高塔的距离，无论该较高塔位于其左侧还是右侧。 最高的塔没有任何贡献，因为不存在更高的塔。 

任务是计算所有非最高塔的最小距离之和。 

高达 200,000 的约束 N 迫使我们远离任何二次策略。 在最坏的情况下，“左右扫描每个塔直到找到更高的塔”的天真检查会退化为 O(N^2)，这将涉及 4 × 10^10 的比较，并且远远超出 2 秒的限制。 

一些边缘情况对于正确性很重要。 如果塔的一侧没有更高的塔，但另一侧有更高的塔，则只有有效的一侧有贡献。 如果两侧都有较高的塔，我们必须选择较近的塔，而不是单向扫描中遇到的第一个塔。 最高的塔必须被完全排除，即使它没有有效的答案。 

朴素定向扫描的一个微妙的失败案例是扫描中遇到的第一个较高的塔不是最近的塔。 例如，身高`[1, 100, 2, 3, 4]`对于索引 0：扫描右侧在距离 1 处命中 100，这是正确的，但对于索引 2，扫描右侧命中 3，然后是 4，然后没有，而最接近的更高实际上是在距离 1 处的 3。正确的解决方案必须始终同时比较两侧。 

## 方法

 蛮力的想法很简单：对于每个索引 i，向外扩展，直到找到满足 H[j] > H[i] 的任何索引 j，并保持所见的最小距离。 这是有效的，因为它直接遵循定义，并且正确性是立即的，因为每个可能的候选者都是按距离递增的顺序检查的。 

问题是成本。 在单调递减数组中，例如`[N, N-1, ..., 1]`，每个元素必须扫描几乎整个数组才能找到左侧唯一较高的元素。 这导致每个元素平均大约需要 N/2 工作，总操作量为 O(N^2)。 

关键的观察结果是，一维数组中的“最近的较大元素”具有结构：对于每个位置，答案仅取决于左侧最近的较大元素和右侧最近的较大元素。 一旦同一侧存在更接近的元素，任何更大的元素都不再相关。 

这将问题转化为经典的单调堆栈场景。 我们可以为每个位置计算线性时间内左侧和右侧最接近的严格更大元素。 一旦知道了这两个候选人，每个位置的答案就是与他们的较小距离。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N^2) | O(N^2) | O(1) | O(1) | 太慢了 |
 | 单调堆栈 | O(N) | O(N) | 已接受 |

 ## 算法演练

 我们通过使用保持高度递减的堆栈计算两侧最近的较大元素来解决该问题。 

1.我们计算一个数组`left[i]`表示从 i 到最近的索引 j < i 且 H[j] > H[i] 的距离。 我们从左到右扫描，同时维护一堆高度严格按降序排列的索引。 当处理 i 时，我们从堆栈中弹出，直到顶部的高度大于 H[i]，因为只有那些才是有效的“左边最接近的”。 最接近的有效值是弹出后的当前堆栈顶部，或者如果堆栈变空则不存在。 
2.我们计算一个数组`right[i]`类似地，但是我们使用相同的单调堆栈思想从右向左扫描。 这给出了索引距离右侧最近的较大元素。 
3. 对于每个索引 i，如果它是最高的元素，我们忽略它，因为两者`left[i]`和`right[i]`根据定义是不相关的。 
4. 对于每一个 i，我们取最小值`left[i]`和`right[i]`并将其添加到答案中。 如果一侧不存在，我们将其距离视为无穷大，因此选择另一侧。 
5. 我们输出总和。 

它之所以起作用是基于堆栈维护的不变量。 在扫描中的任何点，堆栈都包含严格递减的高度序列的索引。 这保证了当我们寻找最近的较大元素时，任何较小或相等的高度都是无关紧要的，可以安全地删除，因为它们永远不能作为当前或未来元素的有效答案。 第一个大于 H[i] 的剩余元素必然是该侧最接近的元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    h = list(map(int, input().split()))
    
    left = [10**18] * n
    right = [10**18] * n
    
    stack = []
    
    # nearest greater to left
    for i in range(n):
        while stack and h[stack[-1]] <= h[i]:
            stack.pop()
        if stack:
            left[i] = i - stack[-1]
        stack.append(i)
    
    stack.clear()
    
    # nearest greater to right
    for i in range(n - 1, -1, -1):
        while stack and h[stack[-1]] <= h[i]:
            stack.pop()
        if stack:
            right[i] = stack[-1] - i
        stack.append(i)
    
    mx = max(range(n), key=lambda i: h[i])
    
    ans = 0
    for i in range(n):
        if i == mx:
            continue
        ans += min(left[i], right[i])
    
    print(ans)

if __name__ == "__main__":
    solve()
```该实现将计算分成两个单调的堆栈传递。 比较`<=`至关重要，因为高度不同，但即使放松假设，保持一致也能确保正确性。 距离存储为大哨兵值，以便缺失的边不会意外影响最小值。 

最大元素的索引计算一次并从最终总和中排除。 这避免了堆栈逻辑内部的特殊情况并保持单调结构的统一。

 ## 边缘情况

 一种关键的边缘情况是所有高度都严格下降。 对于像这样的输入`[5, 4, 3, 2, 1]`，每个元素最接近的较大值总是在左边。 堆栈正确折叠，以便每个元素只能看到之前看到的较大值，从而为除第一个元素之外的所有元素生成距离 1, 1, 1, 1。 单纯的仅右扫描方法在这里会完全失败，因为不存在右侧更大的元素。 

另一个边缘情况是严格递增的序列，例如`[1, 2, 3, 4, 5]`。 这里每个元素最接近的较大元素总是在右边。 单调堆栈确保每个元素与其紧邻的下一个元素匹配，而不会跳过更接近的候选元素。 任何不比较两侧的天真的“在一个方向上发现第一个更大的”方法都会错误地高估早期元素的距离。 

第三种边缘情况是中间的峰值，例如`[1, 5, 2, 4, 3]`。 每个中间元素两边都有竞争的候选者，只有同时跟踪才能保证正确的最小选择。 该算法自然地处理这个问题，因为左数组和右数组是独立计算的，并且仅在最后合并。
