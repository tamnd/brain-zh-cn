 ## 解决方案
 ## 问题理解

 我们得到了 N 个对象的集合，每个对象代表一篇论文。 每篇论文都包含对其他论文的引用列表，形成一个有向图，其中箭头从一篇论文指向它引用的每一篇论文。 该结构保证没有定向循环，因此如果您向前跟踪引用，您将永远无法返回到同一篇论文。 

任务是确定这些论文是否可以排列成一个链，该链仅使用所有论文一次，以便每篇论文都引用链中的下一篇论文。 用图术语来说，我们被问到有向无环图是否包含遵循边缘方向的哈密顿路径。 

约束 N 高达 100,000，总边数高达 500,000 意味着我们必须在线性或近线性时间内操作。 任何尝试显式测试所有排列或所有路径的解决方案都是立即不可行的，因为即使是 O(N^2) 在这种规模下也会太慢。 

一个微妙的点是，我们没有被问到图是否是无向连通的。 一个图可以连接起来，但如果有分支，仍然不满足条件。 相反，多个断开连接的组件已经使得不可能形成覆盖所有节点的单个链。 

一个常见的失败案例来自于假设“非循环”意味着有效的排序会自动起作用。 例如，如果我们有三个节点，其边为 1 → 2 和 1 → 3，则该图是一个 DAG，但无法将所有三个节点排列成一个链，其中每个步骤都遵循一条边，因为在 1 之后我们无法按顺序同时转到 2 和 3。 

另一个失败案例来自于假设任何拓扑排序都有效。 拓扑顺序可能会将节点放置在有效的依赖顺序中，但仍然无法对应于连续节点通过边直接连接的路径。 

## 方法

 强力解释会尝试从每个节点开始构建一条路径，执行 DFS 或回溯，尝试在标记访问节点的同时逐步扩展路径。 在最坏的情况下，每个节点都可以分支到许多其他节点，并且探索所有可能性会导致阶乘或指数行为。 即使对访问状态进行修剪，仍然会探索大量的部分排列，因为图仅被限制为非循环的，而不是线性的。 

关键的观察是，如果存在这样一个完整的链，那么图本质上就会被迫进入近线性结构。 在有效的解决方案中，除了最后一个节点之外的每个节点都必须沿着链有一个“下一个”选择。 这表明整个结构可以使用拓扑顺序进行验证，因为在 DAG 中，任何哈密顿路径都必须显示为有效的拓扑顺序。 

一旦我们计算了拓扑排序，我们只需要检查该排序中的每个连续对是否由有向边连接。 如果成立，则排序本身就是有效的哈密顿路径。 如果它不成立，则不存在哈密顿路径，因为任何有效路径都必须以拓扑顺序出现，并且连续位置之间不存在边表明该图无法支持完整的链。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 通过路径回溯 DFS | O(N!) | O(N) | 太慢了 |
 | 拓扑排序+邻接检查 | O(N + M) | O(N + M) | 已接受 |

 ## 算法演练

 我们将引文结构视为有向图，并使用标准的基于度的拓扑排序过程。

1. 为图构建邻接表并计算每个节点的入度。 这使我们能够识别哪些节点没有先决条件，这意味着没有传入的引用。 
2. 初始化一个队列，其中所有入度为零的节点。 这些节点可以在任何有效的顺序中首先出现，因为没有任何东西依赖于它们。 
3. 重复从队列中删除一个节点，将其追加到拓扑顺序中，并减少其指向的所有节点的入度。 当节点的入度变为零时，它将被添加到队列中。 此过程模拟以有效的依赖关系顺序删除“可用”论文。 
4.处理完所有节点后，我们得到所有论文的拓扑排序。 由于该图保证是非循环的，因此每个节点都将被处理。 
5. 通过检查订单中的每个相邻对来验证此排序是否形成单个链。 对于每个连续的对 (u, v)，我们检查是否存在直接边 u → v。 
6. 如果所有连续对都通过边连接，我们返回 1，因为顺序本身是有效的完整引用链。 否则，我们返回 0。 

### 为什么它有效

 在 DAG 中，任何哈密顿路径都必须遵循拓扑顺序，因为边总是沿着依赖关系前进。 如果存在哈密顿路径，则它定义了所有节点的总顺序。 拓扑排序是相同偏序的另一种线性扩展。 如果图承认哈密顿路径，则所有有效的拓扑排序必须与该路径排序一致，因为反转路径中的任何对都会与有向边的存在相矛盾。 

因此，如果我们计算拓扑排序并发现某些相邻对没有直接连接，则意味着存在路径无法继续的“间隙”，这意味着根本不存在哈密顿路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())
    adj = [[] for _ in range(n)]
    indeg = [0] * n

    for i in range(n):
        parts = list(map(int, input().split()))
        c = parts[0]
        for x in parts[1:]:
            x -= 1
            adj[i].append(x)
            indeg[x] += 1

    q = deque([i for i in range(n) if indeg[i] == 0])
    topo = []

    while q:
        u = q.popleft()
        topo.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    pos = [0] * n
    for i, x in enumerate(topo):
        pos[x] = i

    has_edge = set()
    for u in range(n):
        for v in adj[u]:
            has_edge.add((u, v))

    for i in range(n - 1):
        u = topo[i]
        v = topo[i + 1]
        if (u, v) not in has_edge:
            print(0)
            return

    print(1)

if __name__ == "__main__":
    solve()
```实现首先从引用列表直接构造邻接列表和入度数组。 队列保存所有当前空闲节点，这确保我们始终遵守依赖关系约束。 

生成拓扑顺序后，我们使用一组对构建边的快速查找结构。 这使得连续节点之间的邻接检查为 O(1)，避免了邻接列表的重复扫描。 

最后一个循环是关键的验证步骤。 它强制要求拓扑排序不仅在依赖意义上有效，而且形成不间断的连续路径。 

## 工作示例

 考虑一种情况，该图形成一个简单的链 1 → 2 → 3 → 4。 

| 步骤| 队列| 弹出| 拓扑订单| 入度变化 |
 | --- | --- | --- | --- | --- |
 | 1 | [1] | 1 | [1] | 2 变成 0 |
 | 2 | [2] | 2 | [1,2]| 3 变成 0 |
 | 3 | [3] | 3 | [1,2,3]| 4 变成 0 |
 | 4 | [4] | 4 | [1,2,3,4] | 完成 |

 每个连续的对都有一条直接边，所以答案是 1。这证实了纯链结构被正确识别。 

现在考虑一个分支 DAG，其中 1 → 2 和 1 → 3，2 和 3 之间没有边。 

| 步骤| 队列| 弹出| 拓扑订单|
 | --- | --- | --- | --- |
 | 1 | [1] | 1 | [1] |
 | 2 | [2,3]| 2 | [1,2]|
 | 3 | [3] | 3 | [1,2,3]|

 当检查连续对时，我们发现 1 → 2 存在，但 2 → 3 不存在，因此算法输出 0。这表明，即使该图在拓扑意义上是非循环且完全有序的，但它并没有形成单个哈密顿路径。

 ## 边缘情况

 关键的边缘情况是非循环但立即分裂的图。 例如，节点1指向2和3。算法在拓扑排序中首先处理节点1，然后2和3同时变得可用。 生成的排序会将它们按任意顺序放置，例如 [1,2,3]，但由​​于没有边 2 → 3，因此连续检查失败，正确拒绝输入。 

另一种边缘情况是存在多个有效的拓扑顺序，但只有其中一个可以对应于哈密顿路径。 例如，即使队列允许在不同的步骤中进行不同的选择，任何严格来说不是单链的排序都必然会在连续节点之间引入缺失的边，并且无论如何解决关系，验证步骤都会捕获这一点。
