 ## 解决方案
 ## 问题理解

 我们收到了一系列礼物，每件礼物都有一个首选的“理想”交付日期。 对于每件礼物，我们都必须选择实际的交付日期。 所选择的日期不允许早于理想日期，但可以晚于理想日期。 

问题是 Hermes 总共最多只能在 K 个不同的日子里可用。 在每个选定的日子里，他都可以送出任意数量的礼物。 因此，任务不仅仅是为每件礼物分配一天，而是选择最多 K 个交付天并将礼物分组到这些天。 

如果礼物在 t 天交付，而其理想日期是 d，则会产生 (t − d)² 的惩罚。 目标是将每件礼物分配给最多 K 个选定的交付日之一，尊重 t ≥ d，同时最小化总惩罚。 

问题的结构表明分组比个人作业更重要。 一旦确定了一组交付日期，每件礼物只需选择其中最可行的日期即可，但真正的困难在于选择日期和分组。 

限制因素以特定的方式发挥作用。 当 N 达到 5000，K 达到 20 时，任何尝试探索交货天数的所有子集的解决方案都是不可能的，因为即使从大范围中选择 K 天，组合起来也是巨大的。 同样，任何立方或更差的分区方法都会太慢。 O(N²K) 动态规划解决方案是可以接受的，特别是当转换为 O(1) 时。 

一个微妙的问题是交货天数并不限于给定的 di 值。 一种幼稚的方法可能假设我们只使用现有的理想日子，但这并没有说明。 然而，正如我们将看到的，最优结构自然会迫使每个组的交货日与排序后该组的边界元素一致。 

一个常见的陷阱是认为每件礼物都可以独立地舍入到其 di 或附近选定的日期，而不考虑分组限制。 例如，如果所有礼物的 di 值都很接近，但 K 很小，则分组决策可能会强制共享延迟交付日，从而显着改变处罚。 

## 方法

 暴力策略会尝试将每件礼物分配给最多 K 个交付日之一，并自行选择交付日。 即使我们假设一组固定的候选日，每个礼物也有 K 个选择，给出 K^N 分配。 这是远远不可能的。 

稍微结构化一点的蛮力会在按 di 排序后尝试所有方法将礼物划分为最多 K 组。 对于每个分区，我们将计算每组的最佳交货日。 即使计算分区也是指数级的，因为这成为 N 个元素上的斯特林数式增长。 

关键的观察是，一旦我们按照礼物的理想日期对礼物进行排序，任何最佳分组都会遵循该顺序。 如果一个组包含交错的值，交换只会减少惩罚，因为在凸成本下，较晚的交付日支配较早的交付日。 

排序后，每个组都成为一个连续的段。 现在考虑一个固定段。 假设一组包含值 d_l 到 d_r，并且我们选择交割日 t ≥ 所有这些值，即 t ≥ d_r。 该段的成本为 sum (t − d_i)²。 展开此函数可显示 t 中的凸函数，其无约束最小值是段中 d_i 值的平均值。 但由于所有 d_i ≤ d_r，该平均值也≤ d_r，这意味着约束 t ≥ d_r 迫使最优值恰好位于 t = d_r。 

这简化了一切：每个细分市场的最佳交货日只是其最大元素。 问题变成在排序数组上选择最多 K 个段，其中每个段的成本完全由其右端点决定。 

该结构直接导致对前缀的动态编程，我们尝试所有最后的段边界。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分区和分配| 指数| O(N) | 太慢了 |
 | 具有 K 段的排序数组上的 DP | O(N²K) | O(NK) | 已接受 |

 ## 算法演练

 1. 按照理想的送达日期对所有礼物进行排序。 这确保了任何最佳分组都可以假设在连续范围上运行而不失通用性，因为交叉分配总是可以重新排列而不增加成本。 
2. 预先计算值及其平方的前缀和。 这些将允许以后对分段成本进行恒定时间评估。 
3. 定义一个 DP 状态，其中 dp[i][k] 表示使用恰好 k 个交付天数安排前 i 个礼物的最小总惩罚。 这个公式直接匹配我们最多可以使用 K 个不同天的约束。 
4. 对于每个 dp[i][k]，将最后一段视为涵盖从位置 j+1 到 i 的礼物。 然后使用 dp[j][k−1] 加上将段 [j+1, i] 分配给单个交付日的成本来更新 dp[i][k]。 
5. 通过注意到其最佳交付日为 d[r] 来计算段 [l, r] 的成本。 成本变成 (d[r] − d[i])² 的 [l, r] 中 i 的总和。 使用前缀和，将其展开为涉及 d[i] 和 d[i]² 之和的公式，从而允许 O(1) 计算。 
6. 取每个状态的所有有效 j 的最小值，按 i 和 k 的递增顺序构建 dp。 
7. 存储转换指针，以便在填充 DP 表后，我们可以重建选择了哪些段，从而为每个礼物分配相应的交付日期。 

### 为什么它有效

 正确性取决于两个结构特性。 首先，排序强制最佳组是连续的，因为任何非连续分组都可以重新排列而不改变可行性，同时不会因凸性而增加成本。 其次，在固定段内，在段中应用可行性约束 t ≥ max di 后，最佳共享交货日被迫到达右端点。 这两个事实将原始组合选择分解为一个干净的区间划分问题，DP 准确地捕获了该问题。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, K = map(int, input().split())
    a = list(map(int, input().split()))
    
    arr = sorted([(v, i) for i, v in enumerate(a)])
    vals = [v for v, _ in arr]
    idx = [i for _, i in arr]
    
    ps = [0] * (N + 1)
    ps2 = [0] * (N + 1)
    
    for i in range(N):
        ps[i + 1] = ps[i] + vals[i]
        ps2[i + 1] = ps2[i] + vals[i] * vals[i]
    
    def cost(l, r):
        # segment [l, r], using vals[r] as delivery day
        x = vals[r]
        m = r - l + 1
        s1 = ps[r + 1] - ps[l]
        s2 = ps2[r + 1] - ps2[l]
        return m * x * x - 2 * x * s1 + s2
    
    INF = 10**30
    dp = [[INF] * (K + 1) for _ in range(N + 1)]
    pre = [[-1] * (K + 1) for _ in range(N + 1)]
    
    dp[0][0] = 0
    
    for k in range(1, K + 1):
        for i in range(1, N + 1):
            for j in range(i):
                val = dp[j][k - 1] + cost(j, i - 1)
                if val < dp[i][k]:
                    dp[i][k] = val
                    pre[i][k] = j
    
    best_k = min(range(1, K + 1), key=lambda x: dp[N][x])
    
    ans_sorted = [0] * N
    i, k = N, best_k
    
    while i > 0:
        j = pre[i][k]
        t = vals[i - 1]
        for p in range(j, i):
            ans_sorted[p] = t
        i = j
        k -= 1
    
    ans = [0] * N
    for (v, orig), t in zip(arr, ans_sorted):
        ans[orig] = t
    
    print(*ans)

if __name__ == "__main__":
    solve()
```该实现首先对礼物进行排序，以便段 DP 变得有效。 值和平方的前缀和允许恒定时间计算每个段的二次成本。 

DP表是按照递增的前缀长度和已用交付天数构建的。 每个转换都会尝试扩展最后一个段边界。 重建数组存储每个段开始的位置，然后用于为该段中的所有元素分配单个交付日。 

最后一步将结果映射回原始索引，因为排序只是结构的工具，而不是最终的输出顺序。 

## 工作示例

 ### 示例 1

 输入：```
5 2
50 0 51 10 50
```排序值：```
0, 10, 50, 50, 51
```最终结构的 DP 轨迹：

 | 我| k | 最后分割 j | 段 | 成本| DP |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | [0]| 0 | 0 |
 | 2 | 1 | 0 | [0,10]| (10−0)²+(10−10)²=100 | (10−0)²+(10−10)²=100 100 | 100
 | 3 | 2 | 2 | [50]| 0 | 100 | 100
 | 5 | 2 | 2 | [0..1]，[2..4] | 最优分割 | 0 |

 最佳分组变成两个部分：首先是较小的值，然后是较大的值，每个部分都使用正确的端点作为交货日。 

映射回后的最终分配：```
51 10 51 10 51
```这表明多件礼物共用一个交付日，并且分组主导了个体最优性。

 ## 边缘情况

 当 K 足够大以至于每件礼物都可以形成自己的部分时，就会出现一种边缘情况。 在这种情况下，每件礼物都是自己的一组，指定的交付日期等于其自己的理想日期。 该算法可以自然地处理这个问题，因为 DP 允许 j = i − 1 转换，从而生成零成本的单元素段。 

另一种情况是当 K = 1 时。那么所有礼物必须共享一个交付日，DP 将其强制放入整个阵列的一个段中。 交货日成为最大 di，因为排序后在右端点处段成本最小化。 

第三种情况涉及混合的小值和大值，其中较早的分割显着减少了二次惩罚。 DP 显式评估所有分割点，确保即使是非直观的分割也会被考虑并选择最好的分割点。
