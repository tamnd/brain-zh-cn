 ## 解决方案
 ## 问题理解

 我们得到一个由小写英文字母组成的字符串。 我们可以执行仅在字母表中增加一个字符的操作，例如转动`c`进入`d`或者`a`进入`b`。 字符不能减少，并且`z`是终端。 

在各个位置上应用任意数量的此类增量后，我们获得一个新字符串。 从这个最终字符串中，我们不需要精确匹配任何内容，但我们需要固定字符串`"abcdefghijklmnopqrstuvwxyz"`显示为子序列。 这意味着我们应该能够按升序选择 26 个位置，以便它们拼写字母表。 

任务是决定是否可能，如果可能，则输出一个实现这一目标的结果转换字符串。 如果存在多个答案，则任何有效的答案都可以接受。 

输入大小最多可达 100000 个字符，这会立即排除任何尝试显式探索转换或模拟每个字符所有可能增量的解决方案。 每个字符最多可以递增 25 次，但是以暴力的方式独立地对每个位置执行此操作仍然会导致不必要的重复扫描。 

一个微妙的一点是，我们可以完全忽略子序列中的字符，因此我们不必被迫使用所有字母。 但是，我们使用的每个字符都必须能够按顺序递增到所需的目标字母。 

一种幼稚的方法可能会尝试贪婪地将字母表中的字母分配给位置，而不仔细跟踪可行性，这在早期分配消耗所有可用字符的情况下可能会失败。 

例如，考虑一个像这样的字符串`"abz..."`那里有很多`z`人物出现得早。 天真的贪婪者可能会错误地尝试将早期字母与`z`， 但`z`无法增加，因此会阻止未来的分配。 

另一种失败情况是当字符串全局包含足够的字母但它们不在可用的递增结构位置时。 由于子序列取决于顺序，而不仅仅取决于频率，因此任何解决方案都必须遵守从左到右的匹配约束。 

## 方法

 一个蛮力的想法是考虑每个字符并尝试将其分配给中的目标字母`"abcdefghijklmnopqrstuvwxyz"`，可能是在增加它之后。 对于字母表中的每个位置，我们可以在字符串中向前扫描以找到合适的字符，然后将其标记为已使用并继续。 这本质上是一种贪心匹配。 

从概念上讲，这是可行的，因为每个字符只能向上移动，所以我们永远不需要考虑重新排列字母，只需要考虑后面的字符是否可以满足所需的字母。 然而，如果不小心实现，重复扫描字符串中的每个字母字符会导致 O(26n)，这仍然没问题，但对每个字符的所有增量的更简单的模拟将是每个位置的 O(26n) 或更糟。 

关键的观察是我们只关心字母表中的每个字母是否可以按顺序匹配。 每个字符都贡献一系列可用字母：一个字符`c`可以变成任何字母`c`到`z`。 因此我们可以将每个位置视为提供一个容量区间。 我们想要匹配`'a' → 'z'`依次使用最早可能的有效位置。 

因此，我们扫描字符串一次，对于每个字母字符，我们选择当前字符可以到达的最早未使用的位置。 一旦使用，该位置就固定且不能重复使用。 

这种贪婪是正确的，因为采用最早的有效位置总是为后面的字母留下最大的灵活性。 任何后来的选择只会减少剩余的选择。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个字母的强力扫描 | O(26n) | O(26n) | O(n) | 已接受 |
 | 最优贪心单遍| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们在字符串上维护一个指针并尝试匹配来自`'a'`到`'z'`为了。 

1.从索引开始`i = 0`和目标字母`cur = 'a'`。 我们将为后续构建建立一个选定索引的列表。 
2. 对于每个目标字母`'a'`到`'z'`，从当前索引开始向前扫描，直到找到一个位置`j`这样`s[j] <= cur`。 这个条件确保我们可以增加`s[j]`最多`cur`不违反字母只会增加的规则。 
3. 如果我们到达字符串末尾而没有找到这样的位置，则构造是不可能的，我们输出`-1`。 发生这种情况是因为没有剩余字符可以到达所需的字母。 
4. 当我们找到一个有效的职位时`j`，我们指定它来表示`cur`， 记录`j`，并将扫描起点移至`j + 1`。 
5. 收集完所有 26 个位置后，我们通过复制原始字符串并替换每个选定位置来构造输出字符串`j`与所需的字母。 
6. 输出结果字符串。 

### 为什么它有效

 正确性依赖于单调匹配不变量：在匹配字母表的前 k 个字母后，我们选择了可以实现它们的 k 个位置的最小可能索引集。 因为每个选择的位置都是最早可行的位置，所以任何后来的替代选择只会将匹配向右移动，从而减少剩余字母的可用后缀空间。 由于可行性仅取决于稍后兼容位置的存在，而不取决于先前未使用的灵活性，因此贪婪选择是安全且最优的。 

字符只增加的约束确保了分配之间的独立性：一旦一个字符用于一个字母，它就不能被重复使用，而且也不能向下修改以干扰早期的匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = list(input().strip())
    n = len(s)
    
    pos = []
    i = 0
    
    for c in range(26):
        target = chr(ord('a') + c)
        found = -1
        
        while i < n:
            if s[i] <= target:
                found = i
                i += 1
                break
            i += 1
        
        if found == -1:
            print(-1)
            return
        
        pos.append(found)
    
    for idx, c in zip(pos, range(26)):
        s[idx] = chr(ord('a') + c)
    
    print("".join(s))

if __name__ == "__main__":
    solve()
```该代码首先将字符串转换为可变列表，以便更新高效。 指针`i`强制每个选定的位置严格递增，这是后续顺序所必需的。 

对于每个字母，我们向前扫描，直到找到可以提升到该字母的字符。 比较`s[i] <= target`编码可行性，因为如果`s[i]`已经大于`target`，它不能减少以匹配它。 

一旦分配了所有 26 个字母，我们就会用目标字符覆盖所选索引并重建字符串。

 ## 边缘情况

 一种失败模式是字符串仅包含大字母，例如`z`。 在这种情况下，理论上每个目标字母都可以从`z`，但我们仍然需要 26 个不同的位置。 如果字符串太短，算法会在某个目标字母处失败，因为没有剩余未使用的索引，从而正确返回`-1`。 

另一种边缘情况是存在小字母但排序不佳，例如`"cba..."`。 扫描确保我们仍然按顺序选择有效位置，但较早的大字母会被正确跳过，因为它们无法降级。 

最后一个微妙的情况是，存在有效的选择，但远远延迟到了右侧。 基于指针的扫描保证我们始终选择最早的有效位置，因此我们永远不会意外地消耗未来字母可能需要的后续段。
