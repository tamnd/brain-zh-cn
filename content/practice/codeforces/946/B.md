 ## 解决方案

 ## 问题理解

 我们得到两个正整数，代表两堆的大小。 确定性过程使用非常具体的规则重复修改这两个值：如果一个值至少是另一个值的两倍，我们就从较大值中减去较小值的两倍。 仅当两个值都不至少是另一个值的两倍，或者其中一个值变为零时，该过程才会停止。 

任务不是模拟固定数量的步骤，而是在应用所有可能的减少后确定最终的稳定对。 

约束允许值高达$10^{18}$，这立即排除了逐步模拟。 单个减法步骤可能很便宜，但在最坏的情况下，迭代次数与数字的大小成正比。 例如，从$(10^{18}, 1)$，一个简单的模拟需要大约$5 \cdot 10^{17}$行动，这远远超出了任何可行的时间限制。 

关键难点在于该过程不是对称减法； 仅当一个值至少是另一个值的两倍时才会触发。 这种情况会导致长时间运行，其中一方会迅速缩小，但也会出现角色交替的情况。 粗心的模拟常常会失败，因为它假设只有一侧占主导地位，或者忘记了减少一个变量后，条件可能会立即翻转并启用相反的操作。 

典型的边缘情况是当值在触发减少之间交替时：

 输入：```
12 5
```正确输出：```
0 1
```幼稚的方法可能每次检查只减去一次，并且错过状态更改后立即发生的重复链式减少。 

## 方法

 暴力模拟直接遵循规则：反复检查是否$a \ge 2b$或者$b \ge 2a$，并进行相应的减法。 这是正确的，因为每个操作都准确反映了问题陈述。 然而，每个步骤都会严格减少至少一个变量，并且在最坏的情况下，仅减少相对于其大小的一小部分。 如果一个数字比另一个数字大得多，则说$a = 10^{18}$和$b = 1$，那么每个有效步骤都会减少$a$2，导致大约$5 \cdot 10^{17}$迭代。 

关键的观察结果是，相同形式的重复减法的行为类似于欧几里得算法，但有一点不同：我们不是减去较小值的一个副本，而是按大小块减去它$2b$。 这意味着我们可以用单个整数除法步骤替换许多重复的步骤。 如果$a \ge 2b$，我们希望一次尽可能多次地应用该操作：$$a \leftarrow a \bmod (2b)$$因为每次操作都会减少$a$正是通过$2b$，我们继续下去，直到条件不再成立。 

同样的想法对称地适用于$b$。 这将过程变成类似于欧几里得算法的对数缩减，因为在每个阶段至少有一个变量急剧缩减。 

微妙之处在于，每次批量减少后，我们必须重新评估这两个条件，因为控制可以在$a$和$b$终止前多次。

 | 蛮力 | O(最大(a,b)) | O(1) | O(1) | 太慢了|
 | 最佳 | O(log 最大值(a,b)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们重复应用最大可能的有效减少，直到双方都无法触发操作。 

1. 检查两个值是否均为正值。 如果其中任何一个变为零，则该过程立即结束，因为没有规则可以应用。 
2.如果$a \ge 2b$， 代替$a$和$a \bmod (2b)$。 这将所有重复的减法压缩为一个步骤，因为每个操作都精确地删除$2b$。 
3.更新后$a$，立即重新检查条件，因为减少了$a$可能允许$b \ge 2a$成为现实。 
4. 如果$b \ge 2a$， 代替$b$和$b \bmod (2a)$，原因与上述相同。 
5. 重复直到两个条件都不成立。 

这种排序起作用的原因是每个模运算保留重复有效减法的效果，而不会跳过任何可能改变哪一方占主导地位的中间状态。 

### 为什么它有效

 该过程始终保持不变，即在该阶段期间较大值严格减小，而较小值保持不变。 每次批量减少都会模拟相同合法移动的最大序列。 由于每个模步骤至少将一个数字减少到严格小于另一个数字的两倍，因此系统最终达到两个条件都不成立的状态，与原始过程的终止条件匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())
    
    while True:
        if a == 0 or b == 0:
            break
        
        if a >= 2 * b:
            a %= 2 * b
            continue
        
        if b >= 2 * a:
            b %= 2 * a
            continue
        
        break
    
    print(a, b)

if __name__ == "__main__":
    solve()
```该解决方案直接将过程编码为具有两个对称批量缩减规则的循环。 关键的实现选择是使用模而不是重复减法，这确保每个阶段以恒定的时间运行。 这`continue`语句确保每次减少后，算法立即重新评估两个方向，因为主导关系可能会在单次更新后发生变化。 

订购时必须小心：检查`a`首先是条件，然后是`b`条件与流程结构匹配并避免跳过新启用的转换。

 ## 边缘情况

 一种边缘情况是当这些值已经处于稳定配置时，其中两个值都至少不是另一个值的两倍。 例如，输入：```
7 12
```该算法首先检查$a \ge 2b$，这是错误的。 然后它检查$b \ge 2a$，这也是假的。 循环立即终止并输出$7 12$，匹配正确的行为，因为无法应用任何规则。 

当重复减少将值精确地减少到零时，会出现另一种边缘情况。 例如：```
2 1
```这里，$a \ge 2b$成立，所以$a = 2 \bmod 2 = 0$。 然后，由于一个值​​为零，该过程立即停止，产生输出：```
0 1
```这证实了基于模的归约可以正确处理精确的整除性，而不需要特殊的外壳。
