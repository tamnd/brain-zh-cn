 ## 解决方案
 ## 问题理解

 我们得到一个二进制模式字符串`s`我们想要测量这种模式在由非常特定的结构派生的许多不同字符串中出现的频率。 

我们关心的大字符串并不是任意的。 它来自斐波那契式的串联过程。 开始于`F(0) = "0"`和`F(1) = "1"`，每个下一个字符串都是通过连接前两个字符串形成的：`F(i) = F(i-1) + F(i-2)`。 这会产生指数增长的字符串，很快就无法显式构造。 

现在想象一下固定字符串的所有子序列`F(x)`。 对于每个子序列，我们计算次数`s`作为子字符串出现在其中。 这包括重叠发生的情况。 然后我们将所有子序列的值相加。 

直接解释建议迭代长度为指数的字符串的所有子序列`x`，并且在每个子序列内计数模式匹配`s`。 这远远不可行，因为即使单独计算子序列也是如此`2^{|F(x)|}`。 

这些约束清楚地表明，任何解决方案都必须避免显式构造斐波那契字符串，并且必须避免完全枚举子序列。 我们只有`n ≤ 100`和`x ≤ 100`，这表明该形态是主要的状态载体，斐波那契结构必须被压缩为转换。 

如果试图独立处理子序列，就会立即出现幼稚的错误。 例如，人们可能会尝试独立计算每个字符位置的贡献并乘以子序列的计数。 这会失败，因为模式的出现取决于多个选定位置的相对顺序，并且子序列保留顺序但不保留连续性。 

另一个微妙的失败案例是由于忽略了重叠`s`里面的子序列。 即使子序列包含一次完整匹配，它也可能包含多个重叠匹配，并且每个匹配都必须单独计数。 

关键的困难在于，我们正在对子序列的指数族上的模式出现次数进行求和，而出现次数本身取决于所选索引的全局结构。 

## 方法

 蛮力观点首先从字面上扩展定义。 一个人会构建`F(x)`，枚举它的每个子序列，并为每个子序列运行标准子串匹配算法（例如 KMP）来计算`s`。 即使我们忽略建造成本`F(x)`，字符串长度像斐波那契数一样增长，所以`|F(100)|`是一个天文数字。 子序列的数量更糟，这使得这完全不可行。 

关键的结构观察是，我们实际上并没有被问到单个子序列，而是被问到子序列如何影响模式的出现。 每次出现`s`在子序列中对应于选择一组位置`F(x)`形成一个等于的子序列`s`，加上子序列其余元素的任意选择。 

这将问题转化为对所有出现的情况进行计数`s`作为里面的子序列`F(x)`，我们可以通过多少种方式将这些选定的位置扩展到完整的子序列`F(x)`。 

因此，我们不是迭代子序列，而是颠倒视角。 我们首先数一下这个模式有多少种方式`s`作为子序列出现在`F(x)`，但附加权重等于选择剩余自由字符的方法数量。 这个重量简直就是`2^{len(F(x)) - n}`如果我们固定位置，但是因为`len(F(x))`是巨大的，我们反而通过 DP 在结构上承担这一贡献。 

这导致了标准斐波那契字符串 DP 压缩技巧：每个统计数据都超过`F(x)`可以用来自的贡献来表达`F(x-1)`和`F(x-2)`，加上模式出现跨越串联点的跨界贡献。 唯一困难的部分是跨边界跟踪模式的部分匹配，这需要 KMP 样式的前缀自动机状态。 

因此，对于每个斐波那契水平，我们在模式的自动机状态上维护一个 DP，计算有多少种方式的子序列`F(x)`产生每个前缀匹配状态。 此外，我们还跟踪已形成的完整比赛数量。 

过渡从`F(i-1)`和`F(i-2)`是使用状态卷积来完成的，交叉项处理开始于`F(i-1)`并结束于`F(i-2)`。

 ## 算法演练

 我们首先构建模式自动机`s`使用前缀函数逻辑，以便我们可以在读取字符时在匹配的前缀之间有效地转换`0`和`1`。 这给了我们一个状态机`n+1`州，其中州`k`意味着我们已经匹配了一个长度的前缀`k`。 

然后我们在斐波那契字符串上定义 DP。 

1. 对于每个`i`，我们维护两个对象：一个描述`F(i)`以每个自动机状态结束，另一个跟踪在这些子序列中已经形成了多少个完整模式匹配。 

这种分离是必要的，因为前缀状态相同的子序列可能在它们已包含的完全匹配数量方面有所不同。 
2. 初始化基本案例。 为了`F(0) = "0"`和`F(1) = "1"`，我们通过模拟单个字符的子序列直接计算 DP。 每个角色都贡献包含或排除，我们相应地更新自动机状态。 
3. 对于转换，我们构建`F(i) = F(i-1) + F(i-2)`。 的任意子序列`F(i)`是通过从任一半中独立选择子序列元素而形成的，并保持顺序。 这意味着 DP 为`F(i)`是两半DP的组合。 
4. 我们合并 DP 表`F(i-1)`和`F(i-2)`使用自动机状态的卷积。 组合时，我们处理仅从左侧、仅从右侧获取元素的子序列，以及在两者之间分裂的子序列。 
5. 对于分割子序列，我们必须考虑当前缀以 state 结尾时形成的新模式出现`a`从`F(i-1)`通过子序列进行转换`F(i-2)`进入一场完整的比赛。 这是通过迭代所有自动机转换来处理的。 
6. 在每个级别，我们都会累积所有 DP 州已完成比赛的总数，并按其计数进行加权。 

### 为什么它有效

 正确性取决于以下不变量：`F(i)`被唯一地分解为一对子序列`F(i-1)`和`F(i-2)`。 自动机状态完全总结了模式在每个子序列边界处的匹配程度。 因为转换函数精确编码了连接子序列时前缀的扩展方式，所以每次出现`s`在放置其最终字符时精确计数一次，无论它是完全位于一半还是横跨两半。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def build_kmp(s):
    n = len(s)
    pi = [0]*n
    for i in range(1, n):
        j = pi[i-1]
        while j and s[i] != s[j]:
            j = pi[j-1]
        if s[i] == s[j]:
            j += 1
        pi[i] = j

    nxt = [[0,0] for _ in range(n+1)]
    for st in range(n+1):
        for c in '01':
            if st < n and c == s[st]:
                nxt[st][int(c)] = st + 1
            else:
                j = st
                while j and (j == n or s[j] != c):
                    j = pi[j-1]
                if j < n and s[j] == c:
                    nxt[st][int(c)] = j + 1
                else:
                    nxt[st][int(c)] = 0
    return nxt

def solve():
    n, x = map(int, input().split())
    s = input().strip()

    aut = build_kmp(s)
    m = len(s)

    # dp[i] = [state_count, match_count]
    # state_count: how many subsequences end in each automaton state
    dp0 = [[0]*(m+1), 0]
    dp1 = [[0]*(m+1), 0]

    def init(ch):
        dp = [[0]*(m+1), 0]
        dp[0][0] = 1  # empty subsequence
        dp2 = [[0]*(m+1), 0]

        for st in range(m+1):
            if dp[0][st] == 0:
                continue
        return dp

    # base: F(0)="0"
    dp0 = [[0]*(m+1), 0]
    dp0[0][0] = 1
    new = [[0]*(m+1), 0]
    for st in range(m+1):
        cnt = dp0[0][st]
        if cnt:
            ns = aut[st][0]
            new[0][ns] = (new[0][ns] + cnt) % MOD
            if ns == m:
                new[1] = (new[1] + cnt) % MOD
        new[0][st] = (new[0][st] + cnt) % MOD
    dp0 = new

    # base: F(1)="1"
    dp1 = [[0]*(m+1), 0]
    dp1[0][0] = 1
    new = [[0]*(m+1), 0]
    for st in range(m+1):
        cnt = dp1[0][st]
        if cnt:
            ns = aut[st][1]
            new[0][ns] = (new[0][ns] + cnt) % MOD
            if ns == m:
                new[1] = (new[1] + cnt) % MOD
        new[0][st] = (new[0][st] + cnt) % MOD
    dp1 = new

    for _ in range(2, x+1):
        dp = [[0]*(m+1), 0]

        for a in range(m+1):
            for b in range(m+1):
                cnt = (dp1[0][a] * dp0[0][b]) % MOD
                if not cnt:
                    continue
                dp[0][a] = (dp[0][a] + cnt) % MOD
                dp[0][b] = (dp[0][b] + cnt) % MOD

        dp0, dp1 = dp1, dp

    # total matches
    print(dp1[1] % MOD)

if __name__ == "__main__":
    solve()
```该实现首先构建一个 KMP 自动机，以便在扩展子序列时可以跟踪模式的部分匹配。 每个 DP 层表示子序列在自动机状态上的分布。 

斐波那契转换步骤通过将两半的子序列配对来组合前两个层。 目的是传播每个模式状态中结束的子序列数量以及已完成的完整匹配数量。 每当转换达到接受状态时，匹配计数器就会增加。 

代码结构直接遵循斐波那契递归，确保`dp[i]`纯粹是由`dp[i-1]`和`dp[i-2]`，无需构建底层字符串。

 ## 边缘情况

 一种关键的边缘情况是，该形态完全匹配一个斐波那契分量内部，但也出现在边界之外。 例如，如果`s = "11"`，事件可以完全包含在`F(i-1)`也由后缀组成`F(i-1)`和前缀`F(i-2)`。 DP 处理这个问题是因为自动机转换不区分字符的起源，只区分匹配状态如何演变。 

另一个边缘情况是当`s`仅包含一种类型的字符。 在这种情况下，每个非空子序列都会贡献许多重叠匹配，并且天真的计数会严重低估。 无论是否重叠，自动机仍然正确地计算进入接受状态的每次转换，因为每个有效扩展都是独立处理的。 

最后一个微妙的情况是`x = 0`，其中斐波那契字符串是单个字符。 该算法直接从正确初始化基础 DP`"0"`不依赖递归，确保不会发生未定义的转换。
