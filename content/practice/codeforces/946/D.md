 ## 解决方案

 ## 问题理解

 我们的每周时间表分为几天，每天又分为固定数量的小时时段。 在每个时段，伊万要么有演讲，要么没有。 输入只是一个由 0 和 1 组成的网格，其中 1 表示在该时间安排了一场讲座。 

Ivan 最多允许跳过`k`整个星期的讲座。 在他选择跳过哪些讲座之后，他的日常出勤规则变得非常严格：在任何一天，只要他至少参加一场讲座，他就在当天第一场讲座之前到达，并在最后一场讲座之后立即离开。 这意味着，即使听课之间存在间隙，从第一次听课到最后一次听课的整个连续间隔期间，他仍然留在大学。 

因此，一天的费用不是取决于他参加了多少场讲座，而是取决于做出跳过决定后最早参加的讲座和最晚参加的讲座之间的距离。 如果他跳过一天的所有讲座，则当天的费用为零。 

目标是最多分配`k`以最小化这些每日时间间隔总和的方式跳过所有日期。 

约束足够严格，可以排除任何呈指数增长的情况`k`或每天的讲座数量。 两个都`n`,`m`， 和`k`最多 500，这提出了一个解决方案`O(n * k^2)`或者`O(n * k)`是可以接受的，而像枚举讲座子集这样的事情是完全不可行的。 

一些边缘情况在实践中很重要。 如果一天没有讲座，则贡献始终为零，无论`k`。 如果一天中的所有讲座都保留，则成本只是第一堂课和最后一堂课之间的跨度`1`。 另一种微妙的情况是，当跳课删除除一堂课之外的所有课程时，无论其他地方的间距如何，都会将间隔折叠成一堂课的长度。 

一个天真的错误是认为跳过讲座会线性降低成本。 例如，在这样的一天`100001`，删除中间讲座没有帮助，除非它改变了间隔的端点。 另一个错误是独立对待每个讲座，而实际上成本仅取决于删除后极端选择的端点。 

## 方法

 蛮力观点从每天思考开始。 对于每一天，我们可以选择保留讲座的任何子集，只要我们不超过`k`所有天的总跳过次数。 对于固定子集，我们通过扫描最早和最新保留的讲座来计算每天的成本。 这立即呈指数增长，因为每天就有多达`2^m`子集，以及跨`n`天的组合空间爆炸得远远超出了任何极限。 

结构简化的关键在于，一天内保留的讲座的内部排列并不重要，只关心保留的讲座中的最小和最大位置。 一旦我们确定了一天删除的讲座数量，我们实际上是在尝试选择剩余大小的子集，以最小化其跨度。 该最佳子集始终是已排序的讲座位置列表中的连续块。 

这将每一天简化为一个小的预先计算：对于当天可能的跳过次数，我们计算当天花费的最短时间。 一旦每天被压缩成一个成本数组，该数组以使用的跳过次数为索引，问题就变成了一个经典的背包问题，我们在其中分配的天数最多`k`总跳过次数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数（米/天）| 指数| 太慢了|
 | 最佳DP（日间压缩+背包）| O(n * m^2 + n * k^2) | O(n * m^2 + n * k^2) | O(k) | 已接受 |

 ## 算法演练

 我们首先将每一天转换为一个紧凑的表示形式，告诉我们：如果我们准确地使用`t`跳过这一天，这一天在大学里呆的最短时间是多少。 

1. 收集每天所有讲座的位置。 这些头寸全天都在严格增加。 
2.如果有一天`c`讲座，考虑一下如果我们删除会发生什么`t`其中。 我们会保留`c - t`讲座。 
3.为了最小化时间间隔，我们尝试所有连续的大小组`c - t`在讲师职位的排序列表中。 对于从索引开始的窗口`i`，成本为`pos[i + c - t - 1] - pos[i] + 1`。 
4. 取所有此类窗口中的最小值。 这给出了最佳的支出成本`t`在这一天跳过。 
5. 如果`c - t <= 0`，意味着我们删除所有讲座，成本为零。 
6. 建立每天的成本表后，我们在几天内运行动态规划。 让`dp[j]`表示使用精确处理某些天数前缀后花费的最小总时间`j`跳过。 
7. 对于每一天，我们计算一个新的 DP 数组`ndp`。 对于先前使用过的每个可能的跳过次数`j`，我们尝试分配`t`额外跳转到当天，更新`ndp[j + t]`和`dp[j] + cost_day[t]`。 
8. 我们整天重复这个过程，最终的答案是中的最小值`dp[0..k]`。 

### 为什么它有效

 关键的不变量是每天处理后，`dp[j]`存储所有精确分配方式所花费的最小可能总时间`j`跳过迄今为止所见的日子。 按天压缩是有效的，因为单日的任何最佳解决方案都可以进行转换，以便保留的讲座按照当天讲座的排序顺序形成一个连续的片段，而无需增加成本或改变删除的数量。 背包转换保留了最优性，因为每天的决策仅取决于分配给它的跳过次数，并且一旦每天的成本函数固定，这些决策就是独立的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    
    days = []
    for _ in range(n):
        s = input().strip()
        pos = [i for i, ch in enumerate(s) if ch == '1']
        days.append(pos)

    INF = 10**18
    dp = [INF] * (k + 1)
    dp[0] = 0

    for pos in days:
        c = len(pos)
        
        cost = [INF] * (k + 1)
        
        if c == 0:
            cost = [0] * (k + 1)
        else:
            for t in range(k + 1):
                if t >= c:
                    cost[t] = 0
                else:
                    keep = c - t
                    best = INF
                    for i in range(c - keep + 1):
                        j = i + keep - 1
                        best = min(best, pos[j] - pos[i] + 1)
                    cost[t] = best

        ndp = [INF] * (k + 1)
        for used in range(k + 1):
            if dp[used] == INF:
                continue
            for t in range(k + 1 - used):
                ndp[used + t] = min(ndp[used + t], dp[used] + cost[t])

        dp = ndp

    print(min(dp))

if __name__ == "__main__":
    solve()
```该代码首先将每天转换为讲座位置列表，这使得间隔的推理纯粹是算术。 这`cost[t]`计算对删除后的关键观察进行编码`t`讲座中，最佳剩余集是排序位置上的滑动窗口。 

第二阶段是简单的 DP 合并。 嵌套循环结束`used`和`t`确保我们考虑所有有效的跳跃分布而不超过`k`。 界限`k + 1 - used`防止无效状态并将转换保持在限制范围内。 

一个常见的实施陷阱是忘记删除所有讲座必须产生零成本。 另一个是混淆了“保留计数”和“删除计数”，这会导致窗口大小不正确。 滑动窗口计算必须始终使用`c - t`作为保留讲座的数量。 

## 工作示例

 ### 示例 1

 输入：```
2 5 1
01001
10110
```第一天，讲座地点`[1, 3, 4]`。 跳过 0 次时，最佳间隔为`4 - 1 + 1 = 4`。 跳过 1 次，我们保留 2 个讲座，最好的窗口是`[1,3]`或者`[3,4]`，都给出成本`3`和`2`，所以最小值是`2`。 

第二天持仓量为`[0, 2, 3]`。 0 次跳过的成本是`4`，跳跃成本为 1 时变为`2`。 

现在我们最多分发一个skip。 最好的选择是在能提供更好改进的当天使用跳过，从而获得总的`2 + 3 = 5`。 

| 日 | 使用过的料斗 | 保留窗口| 成本|
 | ---| ---| ---| ---|
 | 1 | 1 | [1,3]| 3 |
 | 2 | 0 | [0,3]| 4 |

 此跟踪显示如何分配单个跳过以减少一天的跨度，同时保持另一天的跨度不变。 

### 示例 2

 输入：```
1 6 2
100001
```职位有`[0, 5]`。 即使 0 次跳过，成本也是`6`。 任何跳过都不会有意义地更改端点，因为只有在删除两个端点后，删除一个端点才会折叠为单个点。 

| 跳过 | 保持设定| 成本|
 | ---| ---| ---|
 | 0 | [0,5]| 6 |
 | 1 | [0] 或 [5] | 1 |
 | 2 | []| 0 |

 两次跳跃后，最佳结果是`0`，表明完全移除消除了所有成本。

 ## 边缘情况

 没有讲座的一天是通过预先计算的位置列表为空来处理的。 所有跳过计数的成本数组都设置为零，这正确地反映了无论如何在其他地方分配跳过，都不会花费时间。 

取消所有讲座的一天变得很重要`k`很大。 在这种情况下，一旦`t`超过讲座数量，成本被迫为零，并且 DP 可以正确地将所有跳过转变为消除整天。 

每天一堂课的最小案例表现正确，因为滑动窗口退化为单个元素，产生成本`1`除非那个讲座被跳过。
