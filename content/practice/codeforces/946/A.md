[CF 946A - 分区](https://codeforces.com/problemset/problem/946/A)

 **求解时间：** 1m 22s

 ## 解决方案
 ## 问题理解

 我们得到一个整数列表，我们可以以任何我们喜欢的方式将该列表分成两组，唯一的规则是每个元素必须恰好属于这两组中的一个。 一组对分数有正向贡献，而另一组对分数有负向贡献。 更准确地说，如果我们称这两个组为$b$和$c$，我们关心的值是中元素的总和$b$减去中元素的总和$c$，并且我们希望使该值尽可能大。 

此设置立即表明每个元素独立地影响最终表达式，具体取决于它所在的组。由于每个元素要么添加一次（如果放入$b$）或减去一次（如果放入$c$），每个元素的决策都是局部的，但目标通过单个全局总和将它们耦合起来。 

约束很小，最多有 100 个数字，每个数字范围在 -100 到 100 之间。这排除了任何高级优化或修剪策略的需要。 即使对所有元素进行指数枚举，在这种规模下在概念上仍然有效，尽管没有必要。 线性或近线性贪婪推理就足够了。 

当所有数字均为负数时，会出现微妙的边缘情况。 天真的直觉可能表明将它们混合在组之间可能有助于平衡值，但由于每个元素都被强制放入一组，因此将负数放入正组实际上会降低分数，而将其放入负组会将其转化为正贡献。 例如，使用输入$[-5]$，将其放入$b$产量$-5$，但将其放入$c$产量$5$，所以最优答案是$5$。 任何假设“正组应该包含更大的数字”而不考虑符号反转的策略都会在这里失败。 

另一个边缘情况是零值。 无论分配如何，零都不会影响总数，但尝试“平衡”组大小或依赖排序的粗心实现可能会因意外更改结构而错误地处理它们，而不会改善目标。 

## 方法

 暴力解决方案考虑每个元素到任一组的所有可能分配$b$或团体$c$。 对于每个$n$元素，有两种选择，这导致$2^n$可能的分区。 对于每个分区，计算两组的总和需要$O(n)$，给出总体复杂度$O(n \cdot 2^n)$。 和$n = 100$，这变得天文数字般巨大并且完全不可行。 

关键的观察结果是表达式$B - C$可以以消除元素之间任何依赖关系的方式重写。 如果一个元素$a_i$被放置在$b$，它贡献$+a_i$。 如果它被放置在$c$，它贡献$-a_i$。 所以每个元素独立贡献$+a_i$或者$-a_i$，我们希望最大化这些签名捐款的总和。 

这立即将问题简化为决定对于每个元素是否$a_i$或者$-a_i$更大。 为了最大化贡献，我们总是选择正值$|a_i|$，因为之间$a_i$和$-a_i$，总是较大的$|a_i|$如果我们正确分配它：正数去$b$，负数去$c$。 

因此，最优策略就是简单地将所有元素的绝对值相加。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n \cdot 2^n)$|$O(n)$| 太慢了|
 | 最佳（符号选择）|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 读取整数列表。 

每个元素都被独立处理，因为它的贡献仅取决于它被分配到哪个组。 
2. 将累加器变量初始化为零。 

这将存储最大可实现值$B - C$。 
3. 对于每个元素$a_i$，计算其绝对值并将其添加到累加器中。 

这对应于选择更好的放置$a_i$在$b$或将其放入$c$，因为这些选择产生$a_i$和$-a_i$分别。 
4.处理完所有元素后，输出累加器。 

步骤 3 背后的推理是解决方案的核心：每个元素独立地做出积极或消极的贡献，并且我们始终选择最大化其贡献的方向。 

### 为什么它有效

 目标函数分解为独立选择的总和：$$B - C = \sum_{i=1}^{n} x_i$$其中每个$x_i$是$a_i$或者$-a_i$。 由于每一项都独立于其他项，因此最大化总数会减少为单独最大化每一项。 选择$\max(a_i, -a_i)$每个指数的收益率$|a_i|$，确保不可能进行局部改进，因此也不存在全局改进。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

ans = 0
for x in a:
    ans += abs(x)

print(ans)
```该解决方案以线性时间读取输入并迭代数组一次。 累加器`ans`直接反映了目标分解为独立的每个元素的贡献。 关键的实现细节是使用`abs(x)`而不是条件分支； 两者是等价的，但绝对值形式降低了符号错误的风险。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    return str(sum(abs(x) for x in a))

# provided samples
assert run("3\n1 -2 0\n") == "3"

# all positive

 ## 边缘情况

 对于单个负元素，例如`[-7]`，算法计算`abs(-7) = 7`，对应于将其放入组中$c$。 如果相反它被放在组中$b$，贡献将是$-7$，这是严格更糟糕的，确认贪婪的选择是正确的。 

对于像这样的零数组`[0, 0, 0]`，无论放置如何，每个元素的贡献都为零。 该算法正确地累加零，而无需做出任何特殊情况决策，并且由于所有分配都是等效的，因此任何重新排列都无法改善结果。
