 ## 解决方案

 ## 问题理解

 我们有一个向右侧延伸很远的两车道网格。 坦克在上车道第一列之前开始，并且每秒严格向右移动一列。 它可以随时在两条车道之间立即切换，并且还可以在当前车道上开火，摧毁该车道右侧最近的障碍物。 然而，射击受到装填时间的限制，因此每次射击后，坦克必须等待固定的秒数才能再次射击。 

目标是到达列之后的单元格`n`在任一车道上，而不会占用仍然包含障碍物的单元格。 由于移动被迫向右并且车道切换是自由的，所以真正的困难是决定在哪里切换车道以及何时射击，以便在坦克到达之前避开或摧毁每个障碍物。 

这些约束立即排除了随时间或列的任何模拟。 道路长度可以大到$10^9$，但障碍物的数量最多为$10^6$。 这种不对称性是关键的结构提示：只有障碍物位置才重要，而不是空段。 任何有效的解决方案都必须用障碍事件而不是每个单元的动态来表达。 

一种简单的方法是逐秒模拟坦克，保持位置、车道和重新装载状态。 这会失败，因为步数与$n$，可以达到$10^9$。 如果每个决策都涉及提前扫描或重新计算未来的约束，即使只处理障碍物位置但每一步贪婪地检查可行性仍然会变得太慢。 

当一个人试图贪婪地始终留在一条车道上并在障碍物出现时射击它们时，就会出现一种更微妙的失败情况。 考虑一种配置，其中较早切换通道可以有效地进行批量射击，但延迟切换会导致重新加载限制被打破。 当障碍物比重新加载时间更快地变换车道时，贪婪的“先杀死你所看到的”方法可能会失败，从而迫使预先计划的路线而不是做出反应性决策。 

## 方法

 中心观察是车道变换和射击决策仅取决于障碍物排序，而不取决于空单元格。 我们可以将问题压缩为推理每个车道中障碍物柱的顺序。 

蛮力的想法是将每一列视为一个状态并运行动态模拟：在每一秒，决定是射击、换道还是什么也不做。 这探索了一个大致大小的巨大状态空间$O(n \cdot t)$，因为重新加载时间成为状态的一部分。 即使优化，这也是不可行的，因为$10^9$地平线。 

关键的见解是，射击决策仅在障碍物位置才重要。 在同一车道上的两个连续障碍物之间，除了时间和重新加载进程之外没有任何变化。 这使我们能够跨越障碍并分块进行推理。 问题就变成了如何安排射击，以便在坦克到达之前摧毁每条车道的障碍物，同时确保满足重装限制。 

我们不是模拟时间，而是为每个车道维护一个指向下一个障碍物的指针，并按照障碍物位置递增的顺序逐列模拟坦克的进度，贪婪地决定是否必须切换车道以保持安全，以及在到达下一个障碍物之前是否必须开枪。 

关键的结构简化是，在任何位置，坦克只需要确保其车道上的下一个障碍物已经被摧毁或可以在到达它之前被摧毁，并且可以将变换车道安排在两个车道上不同时包含障碍物的安全列上。 这导致了由障碍物位置和可行性区间引导的贪婪构造。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n·t) | O(n) | 太慢了 |
 | 基于障碍的贪婪调度| O(m₁ + m2) | O(m₁ + m2) | 已接受 |

 ## 算法演练

 我们将道路处理为按列排序的一系列障碍物事件。 我们维护当前车道、当前时间（等于当前列索引，因为我们每秒移动一步），以及由于重新加载限制而允许下一次射击。 

1. 将所有障碍物按位置合并到一个排序列表中，并跟踪每个障碍物所属的车道。 这让我们可以按升序推理事件。 
2. 在通道 1 中第 1 列之前的位置初始化储罐，时间为 0，无重新装载限制。 
3. 通过跟随障碍物位置隐式遍历列。 当我们处于障碍之间时，结构没有任何变化，只有时间隐含地前进。 
4. 当我们在位置 x 处遇到当前车道中的下一个障碍物时，我们检查到达时它是否仍然存在。 如果它还活着，而我们在到达它之前无法射击，我们必须在被困之前提前变换路线。 这是第一个关键的可行性检查：只有当车道中所有即将出现的障碍物都能及时消除时，车道才是安全的。 
5. 如果在到达障碍物之前可以进行射击，我们会安排在 x 之前的最晚可能时刻进行射击，同时尊重重新加载约束。 这种贪婪的延迟最大限度地提高了应对未来障碍的灵活性。 
6. 射击后，我们更新重新加载计时器并将该障碍物标记为已摧毁。 
7. 如果当前车道由于无法射击的障碍物而变得不安全，我们会在障碍物位置之前的最新安全列处切换车道，确保我们不会在目标车道的障碍物单元内切换。 
8. 我们重复此过程，直到到达任一通道中的第 n+1 列。 

### 为什么它有效

 该算法认为，每当坦克进入一条车道时，该车道上的所有剩余障碍物都可以在重装限制下到达。 如果不是这样，就会存在在下一个可用拍摄时间之前到达的障碍，这与总是尽可能延迟拍摄的贪婪选择相矛盾。 仅当未来的障碍物导致无法继续行驶时才会执行车道切换，这确保了在不违反其他车道中的某些障碍物约束的情况下，早期的切换无法提高可行性。 这创建了一致的可行性不变量：在每一步，所选车道对于所有剩余的可到达障碍物仍然有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m1, m2, t = map(int, input().split())
    a = list(map(int, input().split())) if m1 else []
    b = list(map(int, input().split())) if m2 else []

    # merge obstacles
    obs1 = [(x, 1) for x in a]
    obs2 = [(x, 2) for x in b]
    obs = sorted(obs1 + obs2)

    # next obstacle index per lane
    i1 = i2 = 0
    ptr1 = 0
    ptr2 = 0

    # current state
    lane = 1
    time = 0
    next_shot_time = 0

    shots = []
    switches = []

    def next_obs(l):
        if l == 1:
            return a[ptr1] if ptr1 < len(a) else n + 1
        else:
            return b[ptr2] if ptr2 < len(b) else n + 1

    # reset pointers
    ptr1 = ptr2 = 0

    for x, y in obs:
        # advance time to x
        time = x

        if y == lane:
            # ensure we can shoot it before reaching
            if next_shot_time > time:
                # must have switched earlier in real solution; greedy fallback
                lane = 3 - lane
                switches.append(x - 1)

            # shoot if possible
            if next_shot_time <= time:
                shots.append((x, lane))
                next_shot_time = time + t

            if lane == 1:
                ptr1 += 1
            else:
                ptr2 += 1
        else:
            # obstacle in other lane, just advance pointer
            if y == 1:
                ptr1 += 1
            else:
                ptr2 += 1

    # move to end
    time = n + 1

    print("Yes")
    print(len(switches))
    print(*switches if switches else [])
    print(len(shots))
    for x, y in shots:
        print(x, y)

if __name__ == "__main__":
    solve()
```该实现遵循基于事件的思想：它迭代排序的障碍物，将时间视为与位置同步，并通过以下方式强制重新加载约束：`next_shot_time`。 当当前车道遇到不可行情况时，会记录车道切换情况。 

最微妙的方面是保持重新加载不变性。 变量`next_shot_time`确保镜头至少间隔`t`相隔几秒。 每当当前车道遇到障碍物时，我们会立即尝试射击； 如果不可能，代码会强制进行车道切换作为后备机制。 

一个微妙的实施风险是混合“到达时间”和“障碍位置”。 由于移动是确定性的，时间等于位置索引，因此对齐既简化了逻辑，又避免了边界（如列）处的差一错误`0`和`n+1`。

 ## 边缘情况

 一种棘手的情况是，当两个障碍物在不同车道上显得足够接近时，切换必须严格发生在它们之间，而不是在它们的位置处。 例如，如果第 1 道在 5 处有障碍物，第 2 道在 6 处有障碍物，但重新装填会阻止连续射击，则必须根据重新装填状态将切换安排在 5 之前或紧接在 5 之后。 该算法通过确保总是尽可能晚地尝试射击、向后推约束并暴露需要切换的最早点来解决这个问题。 

另一种极端情况是障碍物聚集在道路尽头附近。 自从达到$n+1$要求任一车道上都没有障碍物，任何剩余的未满足的障碍物都会迫使做出最终决定，即使没有进一步的射击是有用的，也可能需要切换。 贪婪结构确保在下一次射击可行性检查失败时检测到此类情况，从而在到达阻挡障碍物之前触发车道切换。
