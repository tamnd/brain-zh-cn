 ## 解决方案
 ## 问题理解

 我们得到一个有向图，其中每个顶点代表游戏令牌的状态。 令牌从固定顶点开始，两个玩家交替沿着传出边缘移动它。 如果玩家要从没有传出边的顶点移动，他们会立即失败。 游戏还有一个硬上限：如果游戏持续很长时间（最多 10^6 步），则游戏被宣布为平局。 

不同的是，一名玩家正在睡觉，因此一名玩家可以有效地控制游戏的双方。 这将问题从标准的交替游戏变成了自我控制的游走，我们必须在最佳游戏下推理结果，但增加了循环阻止强制终止的约束，因此意味着平局。 

任务是将起始顶点分类为三种结果之一：控制器强制获胜、强制失败或由于能够无限期避免终止而导致平局。 

约束很大：最多 10^5 个顶点和 2·10^5 条边。 这排除了对博弈树的任何模拟。 即使是对游戏状态进行简单的 BFS 也是不可能的，因为每个顶点状态取决于轮到谁，有效地将状态加倍，并且仍然留下指数分支结构。 

关键的难点来自于周期。 一个天真的 DFS 只试图找到一条通往死胡同的路径，它会错误地将任何循环视为可能获胜或失败，而不了解它是否是可逃避的或可执行的。 

一个微妙的失败案例是一个图表，其中每条路径最终都会导致一个循环。 例如，如果所有顶点形成一个循环，则天真的“无死胡同可达”方法可能会根据遍历顺序错误地将其标记为胜利或失败，而实际上这是平局，因为比赛可以无限期地继续而不会到达终端顶点。 

## 方法

 蛮力的想法是将每个状态视为一个游戏位置并模拟所有可能的移动序列。 从一个顶点开始，我们尝试每个传出边并递归地确定对手是否从结果状态中失败。 这是有向图上的标准极小极大递归。 

这种方法原则上是正确的，因为每个仓位的赢或输取决于是否存在导致亏损仓位的走势。 然而，状态空间会因循环而爆炸。 简单的 DFS 会无限地重新访问状态，或者需要对状态进行记忆，这些状态也对移动次数或奇偶校验进行编码，这会显着增加复杂性。 

真正的洞察力是颠倒视角。 我们不是询问某个位置是否获胜，而是使用最终状态的反向推理对位置进行分类。 没有出边的顶点是失败状态。 任何能够迫使对手陷入失败状态的顶点都是胜利。 然而，传播后未证明获胜或失败的顶点必须位于或导致两个玩家都无法强制终止的循环。 

这导致了在反向边上的多源 BFS 以及剩余传出动作的计数器。 我们向外传播失败和获胜标签，并且在完全传播后任何未分类的内容都是绘制区域的一部分。 

实际获胜路径的构建是通过在 BFS 期间存储父指针来完成的，确保我们可以重建终止于终端顶点的有效强制获胜路径。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 DFS/极小极大 | 指数| O(n) 递归堆栈 | 太慢了 |
 | 具有状态传播的反向 BFS | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 我们将游戏解释为有向图上的最短获胜传播问题。

1. 识别所有终端顶点，即没有出边的顶点。 这些玩家会立即失去位置，因为要移动的玩家无法行动。 我们将它们初始化为失败状态。 
2. 构建一个反向邻接表，以便对于每条边 u → v，我们可以有效地将信息从 v 传播回 u。 这是必要的，因为我们从终端状态向后推理。 
3.维护数组`deg[u]`存储每个顶点的出边数。 这会跟踪每个位置有多少步“未解决”。 
4. 运行一个 BFS 队列，该队列初始化为所有终端顶点都标记为丢失。 我们还维护一个状态数组，其中每个顶点都可以获胜、失败或未知。 
5. 当处理失败的顶点 v 时，我们检查所有前驱顶点 u。 如果你对v有优势，那么你可以通过移动到失败的位置来强制获胜。 我们将 u 标记为获胜并将 v 存储为其后继者以进行路径重建。 
6.当处理获胜顶点v时，我们递减`deg[u]`对于每个前任 u。 这代表你的一个选择会导致对手已知的获胜状态。 如果 u 的所有传出动作都被证明会导致对手获胜（意味着 deg[u] 变为零而没有找到失败的孩子），那么 u 本身就会失败。 
7. 继续传播直到无法确定新的状态。 
8. 传播后，检查起始顶点。 如果获胜，则通过遵循存储的父指针来重建路径，直到到达终端失败顶点。 
9. 如果没有获胜但仍然未分类，则它是循环区域的一部分，双方都可以避免终止，因此结果是平局。 
10、否则，就是亏损仓位。 

### 为什么它有效

 该算法根据强制结果维护顶点的单调分类。 仅当顶点直接移动到已确认的失败顶点时，该顶点才会获胜，从而保证强制移动优势。 仅当所有传出动作都导致对手已被证明获胜的位置时，顶点才会失败，这意味着不存在安全动作。 

完全传播后未分类的任何顶点必须位于获胜或失败传播都无法到达的区域中。 这些顶点必然属于循环或仅馈入循环的结构，其中游戏可以无限期地继续而不会到达最终状态。 这完全符合 10^6 步数上限下平局的定义。 

因为传播总是从已解决的状态转移到未解决的状态，并且永远不会逆转决策，所以一旦分配，任何顶点都不会被错误标记。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

n, m = map(int, input().split())

g = [[] for _ in range(n)]
rg = [[] for _ in range(n)]
deg = [0] * n

for i in range(n):
    parts = list(map(int, input().split()))
    c = parts[0]
    for v in parts[1:]:
        v -= 1
        g[i].append(v)
        rg[v].append(i)
    deg[i] = c

s = int(input()) - 1

# state: 0 unknown, 1 winning, 2 losing
state = [0] * n
parent = [-1] * n

q = deque()

# terminal nodes are losing
for i in range(n):
    if deg[i] == 0:
        state[i] = 2
        q.append(i)

while q:
    v = q.popleft()

    if state[v] == 2:
        for u in rg[v]:
            if state[u] == 0:
                state[u] = 1
                parent[u] = v
                q.append(u)
    else:
        for u in rg[v]:
            if state[u] == 0:
                deg[u] -= 1
                if deg[u] == 0:
                    state[u] = 2
                    q.append(u)

if state[s] != 1:
    if state[s] == 0:
        print("Draw")
    else:
        print("Lose")
else:
    print("Win")
    path = []
    cur = s
    while cur != -1:
        path.append(cur + 1)
        cur = parent[cur]
    print(*path)
```该解决方案首先构建前向和反向邻接表。 反向图至关重要，因为所有传播都是从已知结果向后返回到其前任结果。 

这`deg`数组跟踪每个节点有多少个传出边缘仍然“不安全”。 只有当一个节点的所有子节点都被视为获胜位置后，该节点才会变为失败。 

BFS 队列包含状态已知的节点。 从失败的节点，我们立即将前驱节点转换为获胜节点。 从获胜节点开始，我们消除了前任节点的一个退出选项，这可能会迫使他们进入失败状态。 

仅当节点获胜时才会填充父数组，以确保任何重建的路径始终遵循有效的强制获胜移动顺序。 

## 工作示例

 ### 示例 1

 输入图：```
5 6
1 -> 2,3
2 -> 4,5
3 -> 4
4 -> 5
5 -> none
start = 1
```我们跟踪传播：

 | 步骤| 队列节点 | 行动| 状态变化|
 | --- | --- | --- | --- |
 | 1 | 5 | 终端→失去| 5 = L |
 | 2 | 5 | 传播到 4,2 | 4 = W，2 = W |
 | 3 | 4 | 获胜传播| 更新 3 |
 | 4 | 2 | 获胜传播| 更新 1 |
 | 5 | 1 | 变成W | 完成 |

 最终分类：顶点 1 获胜。 

重建遵循父指针：

 1 → 2 → 4 → 5。 

这确认了一条在终端丢失顶点处结束的强制路径。 

### 示例 2

 考虑一个简单的循环：```
3 3
1 -> 2
2 -> 3
3 -> 1
start = 2
```| 步骤| 队列节点 | 行动| 状态变化|
 | --- | --- | --- | --- |
 | 1 | 无终端节点| 没有 deg = 0 个节点 | 没有初始化|
 | 2 | 队列空 | 没有传播| 一切仍未知|

 所有节点均保持未分类状态，因此结果为“绘制”。 

这表明没有退出的循环永远不会解析为赢/输状态。

 ## 边缘情况

 仅由循环组成的图，例如 1 → 2 → 3 → 1，永远不会产生终端节点。 该算法在 BFS 初始化后将所有顶点保留在未知状态。 由于无法从终端条件向后解析任何状态，因此分类仍然不完整，这被正确地解释为平局。 

具有多个出边的顶点，其中一个通向终端节点，其他通向循环，在发现终端邻居后立即获胜。 这说明了为什么从失败状态进行反向传播就足够了：单次逃逸到失败位置就定义了强制获胜，而不管其他边如何。 

以汇点结束的长链可确保传播正确构建完整的获胜路径。 每个前驱都被精确地解析一次，并且父指针重建一个没有歧义的有效序列。
