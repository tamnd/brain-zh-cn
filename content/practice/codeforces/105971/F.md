 ## 解决方案
 ## 问题理解

 本届赛事有`n`团队。 每对球队比赛一次，球队的概率`i`击败球队`j`只取决于他们的实力：更强的球队更有可能获胜，但任何一种结果都有可能。 如果一个团队能够通过一系列胜利达到其他所有团队的水平，则该团队将被视为获胜者，这意味着直接或间接的胜利都算在内。 

任务是在所有可能的锦标赛结果中找到此类获胜者的预期数量。 

输入给出了团队的数量和每个团队的实力。 输出是获胜者的预期数量模`10^9 + 7`。 由于概率是分数，因此计算时需要模逆。 

团队人数较少，`n`最多 14 个。这排除了对所有可能的锦标赛的模拟，因为有`2^(n*(n-1)/2)`可能的结果，但增长速度太快了。 然而，`2^n`子集仍然是可管理的，因为`2^14 = 16384`，因此子集动态规划方法是预期的方向。 

棘手的部分是理解是什么让一组球队获胜。 一个常见的错误是认为最强的球队总是胜利者。 循环是可以存在的，因此较弱的团队仍然可以与较强的团队属于同一个强连接的组成部分。 

例如，考虑三个具有优势的团队`[1, 1, 1]`。 每场比赛的结果都有相同的可能性。 可能的结果是这样一个循环：球队 1 击败球队 2，球队 2 击败球队 3，球队 3 击败球队 1。所有三支球队都是赢家，而不仅仅是一支。 

另一个边缘情况是单个团队。 没有比赛，唯一的球队可以轻松到达每支球队。 对于输入：```
1
5
```答案是：```
1
```仅检查球队是否赢得比赛的解决方案会错误地返回零。 

## 方法

 暴力方法将产生所有可能的锦标赛。 对于每个生成的图，我们可以从每个团队运行图遍历，并计算有多少个团队可以到达所有其他团队。 这是正确的，因为获胜者的定义正是有向锦标赛图中的可达性。 

问题是比赛的数量。 和`n`团队，有`n * (n - 1) / 2`游戏，每场游戏都有两种结果。 因此，可能的图的数量是`2^(n*(n-1)/2)`。 为了`n = 14`，这已经是`2^91`，这是不可能的。 

关键的观察结果是，获胜者总是恰好形成一个强连通分量。 如果一组球队是胜者组，则该组之外的每支球队都必须输给该组内的每支球队。 否则，外部团队也可以达到获胜部分并成为获胜者。 

这提供了一种通过子集构建答案的方法。 我们计算每个子集是获胜的强连通分量的概率。 对于一个子集，它是获胜组件的概率等于该子集内部强连接并击败所有外部团队的概率。 

直接检查每个子集的强连通性仍然不方便。 相反，我们计算增加子集大小的概率。 对于一个子集`S`，从所有球队的概率开始`S`打败外面的所有人`S`。 然后减去真正获胜成分是较小子集的情况`S`。 

循环之所以有效，是因为如果获胜者设置在内侧`S`是某个真子集`T`， 然后`T`必须击败其余球队`S`，与所需的条件完全相同`T`成为整个锦标赛的获胜者。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(2^(n^2))`|`O(n^2)`| 太慢了 |
 | 最佳 |`O(3^n + n^2 * 2^n)`|`O(2^n)`| 已接受 |

 ## 算法演练

 1. 读取优势并预先计算每支球队击败其他球队的概率。 的价值`i`殴打`j`是`a[i] / (a[i] + a[j])`在模运算下。 
2. 预计算`win[mask]`，所有球队都在里面的概率`mask`击败外面的所有队伍`mask`。 

对于固定子集，这是从子集到其补集的所有交叉边的乘积。 由于相同的子集查询重复出现，存储这些值可以避免重新计算。 
3. 按照团队数量的递增顺序处理子集。 对于每个子集`mask`, 初始化`dp[mask]`和`win[mask]`。 

这表示整个子集是获胜组件的事件，忽略了只有部分强连接的可能性。 
4. 迭代所有非空真子掩码`sub`的`mask`。 删除以下情况`sub`是实际获胜者的组成部分。 

删除的贡献是：`dp[sub] * probability(sub beats mask - sub)`因为较小的组成部分必须主导该子集的其余团队。 
5. 移除所有较小的组件后，`dp[mask]`恰好变成概率`mask`是获胜者的组成部分。 添加`popcount(mask) * dp[mask]`到答案。 

不变量是在计算子集之后，`dp[mask]`包含以下概率`mask`它本身是锦标赛排序中的第一个强连接组件。 较小的获胜组件已被考虑并删除，因此不存在无效案例。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    inv = [0] * (2 * 10**6 + 1)
    for i in range(1, 2 * 10**6 + 1):
        inv[i] = pow(i, MOD - 2, MOD)

    prob = [[0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            if i != j:
                prob[i][j] = a[i] % MOD * inv[a[i] + a[j]] % MOD

    total = 1 << n
    win = [1] * total

    for mask in range(total):
        cur = 1
        for i in range(n):
            if mask >> i & 1:
                for j in range(n):
                    if not (mask >> j & 1):
                        cur = cur * prob[i][j] % MOD
        win[mask] = cur

    dp = [0] * total
    ans = 0

    for mask in range(1, total):
        cur = win[mask]
        sub = (mask - 1) & mask
        while sub:
            if sub != mask:
                cur -= dp[sub] * win[sub | 0] % MOD * 0
                cur %= MOD
            sub = (sub - 1) & mask

        sub = (mask - 1) & mask
        while sub:
            other = mask ^ sub
            if other:
                cur -= dp[sub] * get_cross(sub, other, prob, n) % MOD
                cur %= MOD
            sub = (sub - 1) & mask

        dp[mask] = cur
        ans = (ans + cur * (mask.bit_count())) % MOD

    print(ans)

def get_cross(a, b, prob, n):
    res = 1
    for i in range(n):
        if a >> i & 1:
            for j in range(n):
                if b >> j & 1:
                    res = res * prob[i][j] % MOD
    return res

if __name__ == "__main__":
    solve()
```该实现直接遵循子集递归。 概率矩阵将每个成对获胜概率存储一次，避免重复的模逆计算。 

这`win`数组存储子集支配其之外的所有内容的概率。 在动态规划阶段，每个较小的可能获胜者分量都会被减去。 

两个嵌套子集循环是昂贵的部分。 他们负责`3^n`复杂性是因为每个团队要么位于当前子集内，要么位于较小的子组件内，要么位于两者之外。 这是可以接受的，因为`n`只有14岁。

 ## 边缘情况

 对于单个团队，包含该团队的子集没有外部对手。 其优势概率为 1，动态规划值仍为 1。 答案增加了一个，因为唯一的团队可以从其自身到达。 

同等实力下，没有哪支球队占据优势。 该算法并不假设存在最强的团队。 它通过子集循环计算每个可能的强连接组件大小，从而正确捕获多支球队成为获胜者的锦标赛。 

对于实力高度不平等的情况，较强的球队很有可能占据主导地位，但较弱的球队偶尔也能获胜。 概率计算使用模运算而不是浮点值，因此可以准确地保留微小的概率。
