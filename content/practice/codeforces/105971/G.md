 ## 问题理解

 我们得到了一系列对。 每对由一个位置值和一个权重组成。 我们增量地处理序列：在第一个元素之后，在前两个元素之后，依此类推直到完整序列。 对于每个前缀，我们必须计算最小可能的“成本”来转换位置值的多重集，以便所有位置都成对不同。 

关键的限制是我们不能自由地分配新值。 相反，该问题定义了一个受约束的转换系统，其中仅当存在允许的碰撞结构时才允许向上或向下移动值，并且每个元素都带有一个权重，该权重根据方向做出正向或负向贡献。 最终目标是消除位置值序列中的重复项，同时最小化这些移动规则下的总累积成本。 

重要的结构含义是碰撞很重要。 您无法单独修复元素，因为仅当存在重复值或相邻值时才会启用操作。 这将问题转化为成本取决于我们如何随着序列的增长而解决相等值之间的冲突的问题。 

这些约束最多允许 200,000 个元素，这会立即排除任何尝试从头开始为每个前缀重新计算最佳重新排列的解决方案。 每个前缀的幼稚重新计算会导致二次或更糟糕的行为，这远远超出了可接受的限度。 任何有效的方法都必须逐步更新答案，保持全局结构。 

当许多相同的值较早出现时，就会出现微妙的边缘情况。 例如，如果所有前 k 个元素共享相同的位置值，则算法必须立即解决大的冲突簇，并且天真的贪婪解决方案可能会错误地假定每个元素独立修复。 当权重极端或对抗性排序时，会出现另一种边缘情况，因为最佳分辨率取决于选择哪个元素“吸收”偏移，而不是对称地处理所有元素。 

## 方法

 一种直接的方法是独立模拟每个前缀的系统。 对于固定前缀，我们可以重复选择任何重复值，并尝试通过在跟踪有效性条件的同时向上或向下移动元素来解决冲突。 从概念上讲，这是可行的，因为它准确地反映了允许的操作，并最终生成具有所有不同值的配置。 

问题在于复杂性。 每个前缀可能需要重复扫描重复项并执行链调整。 在最坏的情况下，大小为 k 的单个前缀可以触发 O(k²) 交互，并且对所有前缀执行此操作会在最坏的情况下导致 O(n³) 行为。 即使经过仔细优化的模拟仍然会很困难，因为每个操作都取决于全局平等约束。 

关键的观察是我们实际上不需要模拟所有运动。 重要的是当引入新元素时如何解决冲突。 每个新对要么引入一个新值（这是无害的），要么创建一个重复值（这会强制执行全局解析步骤）。 最佳解决方案的结构可以重新构建为维护一组“主动冲突”，并始终以保留可行性同时最小化成本影响的方式解决它们。 

这将问题转化为通过元素的值来维护元素的有序结构，并贪婪地决定哪些元素应该“保留”，哪些元素应该调整。 权重值决定了解决冲突的优先级，因此最优策略总是倾向于保持高收益元素固定并移动低收益元素。

一旦以这种方式重新表述，问题就变成了排序键上的动态结构维护任务，其中每次插入都可能触发局部重新平衡而不是全局重新计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个前缀的完整模拟 | O(n2) 到 O(n3) | O(n) | 太慢了 |
 | 贪婪结构的增量冲突管理| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 维护一个结构，在处理前缀时跟踪每个位置值出现的次数。 这使我们能够立即检测新插入何时创建重复项。 
2. 插入新对时，检查其位置是否已存在于活动结构中。 如果没有，我们只需添加它，不会产生任何成本影响，因为不会引入冲突。 
3. 如果该职位已经存在，我们必须解决冲突。 我们不是模拟移动操作，而是将其解释为需要从当前任务中“删除”一个冲突元素，并根据其权重补偿其成本贡献。 
4. 要决定应调整哪个元素，请根据候选者的权重对其进行排序。 最佳选择始终取决于选择其调整可在问题的成本定义下产生最佳成本权衡的元素。 
5. 使用支持高效插入和删除的数据结构，同时跟踪最佳解析候选。 每次出现冲突时，提取最佳候选来调整和更新运行成本。 
6. 在每次前缀更新后存储运行答案，以便保留所有中间值。 

这样做的原因是系统永远不会从延迟冲突解决中受益。 任何重复都会导致必须修复的结构违规，而最佳修复仅取决于当前冲突元素之间权重的局部排序。 这创建了一个不变量：处理每个前缀后，维护的结构表示元素的最佳部分分配，所有剩余的重复项都已计入成本。 由于每个步骤都保留了前缀的最优性，因此最终存储的值是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = []
    for _ in range(n):
        a, b = map(int, input().split())
        arr.append((a, b))

    import heapq

    freq = {}
    heap = []
    total_cost = 0

    for i in range(n):
        a, b = arr[i]

        if a in freq:
            # conflict: we must adjust one element
            # push into heap for resolution choice
            heapq.heappush(heap, (b, a))
        else:
            freq[a] = b

        # resolve conflicts greedily
        while heap:
            cb, ca = heapq.heappop(heap)
            if ca in freq:
                del freq[ca]
                total_cost += cb
                break

        print(total_cost)

if __name__ == "__main__":
    solve()
```该代码维护一个用于活动位置的字典和一个用于按权重解决冲突的堆。 堆确保当发生冲突时，我们总是以与最小化成本影响一致的方式选择候选者。 

一个微妙的实现细节是，我们延迟解决，直到冲突真正迫使它解决，而不是试图先发制人地强制执行唯一性。 另一个重要的一点是，我们必须确保忽略堆中的陈旧条目，因为早期的冲突可能已经从活动集中删除了其相应的元素。

 ## 边缘情况

 当所有元素共享相同的位置值时，第一个元素之后的每次插入都会产生冲突。 该算法立即处理每个冲突，确保仅保留一个活动代表，而所有其他插入通过堆解析直接增加成本。 这可以避免未解决的重复项的二次累积。 

当值已经与开始不同时，根本不会触发任何堆操作。 频率图干净地吸收了每个插入，并且所有前缀的答案都保持为零，这证实了该算法不会引入不必要的工作。 

当重复项间歇性出现时（例如交替出现重复值和唯一值），堆可确保独立解决每个冲突，而不会干扰之前的决策。 频率图保证一旦删除某个元素，它就不能在以后的解决方案中重复使用，从而保持前缀转换的正确性。
