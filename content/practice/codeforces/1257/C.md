 ## 解决方案
 ## 问题理解

 我们有几个数组，对于每个数组，我们需要找到具有严格多数元素的最短连续段。 如果一个段包含至少两个元素，并且存在一个值，该值在该段内的频率严格大于每个其他值的频率，则该段被认为是有效的。 

此条件相当于说该细分具有唯一的最频繁值，并且该值严格地比任何竞争对手都更频繁。 如果不存在这样的段，我们返回-1。 

测试用例的输入量很大，元素总数高达 200,000 个。 这立即排除了任何显式检查所有子数组的解决方案。 二次或三次方法将尝试进行 n2 或 n3 段检查的顺序，即使对于单个大型测试来说，这也太慢了。 

关键的困难在于，统治并不仅仅是存在重复。 像这样的一段`[1, 2]`即使两个元素不同也是无效的，而`[3, 3]`是有效的，因为一个值严格占主导地位。 更微妙的是，像这样的片段`[3, 2, 3, 2, 3]`有效，因为 3 比任何其他值出现的次数都多，即使多个值重复也是如此。 

一个常见的错误是假设任何重复项立即意味着长度为 2 的有效答案。当重复项相距较远或多个值在短段内同等竞争时，这种情况就会失败。 另一个失败案例来自于试图贪婪地扩展或缩小窗口，而没有认识到最佳段是由任何值的最接近的重复确定的。 

## 方法

 强力解决方案将枚举每个子数组，计算其中的频率，并检查一个值的频率是否严格高于所有其他值。 即使我们增量地维护频率图，每个测试用例仍然有 O(n²) 个子数组，并且更新或检查优势成本为 O(1) 到 O(n)，导致最坏情况的 O(n³)。 对于总共 200,000 个元素，这是完全不可行的。 

关键的观察是我们并不是在寻找像最大和或最长属性窗口这样的全局结构。 我们只关心已经占据绝对多数的最小部分。 一旦某个值重复，最小的结构就必须出现，因为一个值除非出现至少两次，否则无法成为主导。 一个值加强其主导地位的最短方法是获取该值的两个相邻出现并包含它们之间的所有内容。 任何候选最佳段必须包含在两个相等元素之间的某个间隔内。 

这将问题简化为跟踪每个值的两个连续出现之间的最小距离。 如果一个值出现在位置 i 和 j 处，则该段`[i, j]`是一个候选者，它的长度是`j - i + 1`。 在所有值中，最小的区间就是答案。 

这是有效的，因为任何受控段都必须包含在其中至少出现两次的值。 缩小该段直到它仅跨越该主导值的第一次出现和最后一次出现之间并不能打破主导性，只能减少长度。

 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(n) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 我们维护一个字典，存储每个值出现的最后一个索引。 这让我们可以在看到某个值重复出现时进行检测。 
2. 当我们从左到右扫描数组时，对于值为 x 的每个位置 i，我们检查 x 之前是否已经见过。 如果有，我们计算 i 和前一次出现之间的距离。 
3. 这个距离加一就是候选答案，因为它代表 x 至少出现两次的片段。 
4. 我们更新所有此类对的最佳答案。 
5. 我们将 x 最后出现的位置更新为 i。 
6. 扫描完成后，如果没有找到任何重复值，则返回-1。 否则我们返回最小候选长度。 

关键思想是每个有效的受控段必须包含至少一个重复值，并且该值的最佳可能段始终位于两个连续出现之间。 任何超出这个范围的额外元素只能增加长度，而无助于统治。 

### 为什么它有效

 考虑任何占主导地位的细分市场。 令 v 为其主导值。 由于 v 的频率严格高于该段中任何其他值，因此它必须至少出现两次。 获取该段内 v 的第一次和最后一次出现。 它们之间的子数组仍然至少包含 v 的两次出现，并且删除外部元素不会增加相对于该减小的间隔内的 v 的任何竞争频率。 因此，v 的最佳片段总是由某些事件对捕获，并且检查所有相邻的相等值对足以找到全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        a = list(map(int, input().split()))

        last = {}
        ans = float('inf')

        for i, x in enumerate(a):
            if x in last:
                ans = min(ans, i - last[x] + 1)
            last[x] = i

        print(-1 if ans == float('inf') else ans)

if __name__ == "__main__":
    solve()
```该解决方案依赖于每个测试用例一次通过。 字典`last`存储每个值的最新索引。 每当发现重复时，我们立即计算候选片段长度。 这`+1`是必不可少的，因为索引定义的是差异，而不是长度。 

一个常见的实现错误是忘记将答案初始化为无穷大，并错误地将未见过的情况视为有效。 另一个微妙的问题是在计算候选值后无法更新最后一次出现的情况，这会错误地比较非连续的出现而不是相邻的出现。
