 ## 解决方案
 ## 问题理解

 我们有一个地铁系统，其中车站是节点，每条地铁线路都是通过其中一些车站的固定路径。 每条线路都有该线路上每对相邻车站的行驶时间。 关键的问题在于，一条线路上的火车不会连续运行，而是每隔一段时间从线路的两个端点定期发车。`d`时间单位，然后沿着固定段行程时间的线路移动。 

如果火车在某时刻从某个终点出发`k·d`，它将按顺序经过该线路上的每个车站，因此每个车站都会看到火车在可预测的时间从两个方向到达。 这意味着车站不是一个具有静态边的简单图节点，而是一个具有“当向给定方向行驶的火车可用时”的重复时间表的节点。 

林克目前在家。 如果他按时醒来`s`，他需要`t3`到达车站的时间`1`。 从车站出发`n`，到达后，他需要另一个`t4`是时候到达目的地 BIT 了。 他必须到达车站`n`不迟于时间`t2 - t4`。 目标是选择最晚可能的唤醒时间`s`（不早于`t1`）这样他仍然可以到达车站`n`及时使用地铁系统。 

重要的隐藏结构是，通过地铁的旅行时间取决于在每个车站等待下一趟列车，而这些等待时间取决于绝对到达时间，而不仅仅是图形结构。 这使得该问题成为与时间相关的最短路径问题，并结合了最佳起始时间的搜索。 

约束允许最多`2 × 10^5`车站及最多`10^5`行，时间值高达`10^9`。 这排除了随着时间的推移进行任何模拟或状态的幼稚扩展。 最短路径计算在图大小上必须接近线性对数，并且任何对时间的依赖都必须以每条边的恒定时间计算。 

当火车存在但与到达时间不一致时，就会出现微妙的故障情况。 例如，如果某个时间点访问了一个站点`7`但下一趟火车到达`8`，一个天真的假设“每隔一段时间就存在一列火车”`d`所以我们总是可以立即继续”会导致低估旅行时间。另一个失败的情况是假设早点开始总是更好；在周期性系统中，早点开始实际上可能会错过良好的对齐并导致时间表变慢。

 ## 方法

 暴力策略会尝试每一个可能的唤醒时间`s`，模拟全程，查看是否在期限内到达。 对于每次模拟，我们将在时间相关图上运行最短路径，其中每次松弛都会计算一条线上的下一个可用出发点。 即使每次模拟都使用 Dijkstra，这也会变得太慢，因为`s`范围可达`10^9`，每次运行的成本约为`O((n + m) log n)`。 这将远远超出限制。 

关键的观察结果是，对唤醒时间的唯一依赖是站的起始时间戳`1`。 一旦我们确定了开始时间，剩下的旅程就通过与时间相关的最短路径来确定。 这定义了一个函数`f(s)`将开始时间映射到车站最早到达时间`n`。 至关重要的是，延迟出发不能以任何不平凡的方式改善到达时间，从而打破单调性：稍后出发要么保持相同的时间表对齐，要么将每个可到达的出发时间提前，因此`f(s)`是非减的。 

这种单调性使我们能够二分搜索最新的可行唤醒时间。 对于固定候选人`s`，我们使用修改后的 Dijkstra 计算最早到达时间，其中每条边使用线路周期内的模算术计算下一个火车出发时间。 如果在期限内得到结果，我们稍后再尝试； 否则我们减少`s`。 

唯一剩下的困难是有效地计算沿线的转换。 线路上的每个站都有两种周期性到达模式，每个端点各有一种。 从车站出发`u`在线的`i`，我们预先计算它沿该线到两个端点的距离。 然后，在某个时间`t`, 下一趟可用的火车经过`u`从给定方向的距离由下式确定：`k = ceil((t - offset) / d)`, 给出出发时间`k·d + offset`，然后我们添加到邻近站点的边缘旅行时间。 

这使每次松弛保持 O(1)，因此每次 Dijkstra 运行都是高效的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对所有开始时间进行暴力破解 | O(T·(n + m) log n) | O(T · (n + m) log n) | O(n + m) | 太慢了 |
 | 二分查找 + 时间相关的 Dijkstra | O(log T · (n + m) log n) | O(log T · (n + m) log n) | O(n + m) | 已接受 |

 ## 算法演练

 我们首先预先计算每条线路上每个车站的结构信息。 对于每条线路，我们计算距左端点的前缀距离，因此我们知道从线路起点到任何车站的行程时间。 我们还通过反转直线来计算距右端点的对称距离。 

这一步是必要的，因为它允许我们在 O(1) 内计算火车到达任何车站的时间表，而不是模拟沿线的移动。 

接下来，我们定义固定唤醒时间的可行性检查`s`。 

1.我们在车站设定出发时间`1`作为`s + t3`。 这代表 Link 可以开始使用城域网络的最早时刻。 
2. 我们从车站运行改装的 Dijkstra`1`，其中每个节点状态是一个站点和当前时间。 初始状态是`(station 1, time s + t3)`。 
3. 从车站放松边缘时`u`到邻近车站`v`沿着某条线，我们计算下一趟可用的火车经过`u`朝那个方向。 我们使用预先计算的偏移量和周期`d`找到不早于当前时间的最小出发时间。 
4. 到达时间`v`是这个出发时间加上该航段的旅行时间`(u, v)`。 我们更新了已知的到达时间`v`如果这样就更好了。 
5. Dijkstra结束后，我们检查是否最早到站时间`n`至多是`t2 - t4`。 如果是的话，这个唤醒时间是可行的。 

最后我们进行二分查找`s`在范围内`[t1, t2]`。 对于每个中点，我们都会进行可行性检查。 最大的可行值就是答案。 如果即使`s = t1`失败，我们输出`-1`。 

### 为什么它有效

 正确性取决于两个属性。 首先，最短路径计算在时间相关的边缘成本下是有效的，因为每次松弛总是使用到达后最早可能的出发，因此它永远不会跳过更好的未来机会。 其次，可行性在唤醒时间上是单调的：增加`s`将所有到达时间向前移动，如果之前不存在则无法创建新的有效路线。 这确保二分搜索正确地隔离最大可行睡眠时间。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def ceil_div(a, b):
    if a <= 0:
        return 0
    return (a + b - 1) // b

def check(s, t1, t2, t3, t4, n, adj, line_info):
    start_time = s + t3
    dist = [INF] * (n + 1)
    dist[1] = start_time
    pq = [(start_time, 1)]

    while pq:
        t, u = heapq.heappop(pq)
        if t != dist[u]:
            continue
        if u == n:
            return t <= t2 - t4

        for (v, d, off, w) in adj[u]:
            if t < off:
                k = 0
            else:
                k = (t - off + d - 1) // d
            depart = off + k * d
            arrive = depart + w

            if arrive < dist[v]:
                dist[v] = arrive
                heapq.heappush(pq, (arrive, v))

    return dist[n] <= t2 - t4

def solve():
    t1, t2, t3, t4 = map(int, input().split())
    n, m = map(int, input().split())

    adj = [[] for _ in range(n + 1)]

    for _ in range(m):
        k, d = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        pref = [0] * k
        for i in range(1, k):
            pref[i] = pref[i - 1] + b[i - 1]

        total = pref[-1]

        for i in range(k - 1):
            u = a[i]
            v = a[i + 1]

            off_f = pref[i]
            off_b = total - pref[i]

            adj[u].append((v, d, off_f, b[i]))
            adj[v].append((u, d, off_b, b[i]))

    def ok(s):
        return check(s, t1, t2, t3, t4, n, adj, None)

    if not ok(t1):
        print(-1)
        return

    lo, hi = t1, t2
    ans = t1

    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans - t1)

if __name__ == "__main__":
    solve()
```邻接构造将每条地铁线路变成具有周期性时间表的有向边。 每个边都存储周期`d`，相位偏移`off`描述火车何时向前或向后经过该端点，以及该路段的行驶时间。 

Dijkstra 例程是标准的，只是边缘松弛使用计算的出发时间而不是固定权重。 表达式`(t - off + d - 1) // d`查找与列车时刻表一致的下一个周期倍数。 这是处理时间依赖性的唯一地方。 

二分搜索包装了此可行性检查并返回最大额外睡眠时间。

 ## 边缘情况

 一个重要的情况是当站`n`结构上是可以实现的，但时间表错位使其不可能。 在这种情况下，Dijkstra 仍然会探索节点，但绝不会放松到达的路径`n`在截止日期之前。 即使底层图已连接，检查函数也会正确返回 false。 

另一种情况是等待占据了出行时间。 如果 Link 在车站出发时刻后到达，算法会强制进行完整的等待。 这是正确处理的，因为下一次出发是使用上限划分来计算的，确保不会发生非法“即时登机”。 

第三种情况是最佳唤醒时间恰好是`t1`。 二分查找必须通过初始化答案来正确处理这个问题`t1`并在寻找更高值之前验证可行性。
