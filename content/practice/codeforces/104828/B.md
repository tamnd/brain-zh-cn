 ## 问题理解

 我们得到了几叠卡片。 每个堆栈包含一些不同的整数，并且全局所有卡值形成一个排列，因此每个值在所有堆栈中只出现一次。 

一场比赛由多轮组成。 在一轮中，我们必须准确选择`k`其索引严格递增的不同堆栈。 从每个选定的牌堆中，我们只挑选一张未使用的牌。 在一轮内，所选择的`k`按堆栈索引顺序列出时，卡牌值必须严格递增。 

在连续的轮次之间，游戏施加了一个全局约束：下一轮选择的每个值必须大于上一轮选择的每个值。 因此，如果我们按时间顺序写入所有选定的值，则序列是严格递增的，并且每一轮都是一个连续大小的块`k`。 

一旦我们无法形成另一个有效回合，该过程就会停止，任务是计算我们可以完成多少个完整回合。 

限制很大，卡牌总数最多一百万左右，堆叠最多二十万张。 任何通过简单地扫描所有堆栈来重复尝试构建轮次的解决方案都将太慢，因为即使是单轮也可能会花费线性时间，并且在最坏的情况下可能有多达数十万轮。 

一个关键的结构边缘情况是堆栈索引和值“未对齐”。 例如，假设我们贪婪地选择最小的可用值而不考虑堆栈顺序。 我们可能会选择一组`k`堆栈索引不按照与值相同的顺序增加的值，使得即使存在有效组合，该轮也无效。 

当堆栈中的值未按固定顺序获取时，会出现另一种故障模式。 我们必须始终从堆栈中获取最小剩余值的天真假设是错误的，因为有时跳过一个小值对于保留其他堆栈的未来可行性是必要的。 

## 方法

 暴力破解的解释很简单：模拟游戏。 在每一轮中，考虑所有的选择方式`k`堆叠，尝试从每张牌中挑选一张既满足轮内排序约束又满足全局递增约束的牌，然后选择保持游戏继续进行的最佳可能选择。 这立即变成了组合。 即使选择单轮也涉及在约束下选择有效的堆栈递增子序列之类的事情，并且有指数级的多种选择。 

即使我们修复了单轮的策略，例如通过按升序扫描值来贪婪地构建递增序列的堆栈，我们仍然必须保持跨堆栈的动态可用性。 由于每张卡都使用一次，因此我们会重复更新结构，并且最多可更新`n + m`这很容易变成操作`O(mn)`在最坏的情况下。 

关键的观察结果是，全局约束迫使整个过程的行为就像我们正在按值的递增顺序消费排列一样。 一旦使用了一个值，在以后的回合中就不会再出现更小的值。 因此，任何时刻唯一有意义的状态是：对于每个堆栈，哪些值保持未使用，以及其中哪个值是最小的可用值，因为任何未来的选择都只会考虑增加值。 

这将问题减少到重复提取组`k`来自堆栈中当前“可用的下一个候选”集合的元素，具有兼容性约束，即在组内，索引必须与值顺序对齐。 

关键的见解是，在单个回合内，由于值在全局范围内严格递增，因此我们可以通过按递增顺序扫描值并选择那些堆栈索引保持序列递增的值来贪婪地构建回合。 这将每一轮变成当前活跃候选者的最长递增子序列问题，但长度被截断`k`。 

为了保持跨轮的效率，我们始终为每个堆栈维护其下一个未使用的值，并且我们使用按值排序的全局结构来支持贪婪选择。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对所有选择进行强力模拟 | 指数| O(n) | 太慢了 |
 | 贪婪有序候选人 + 每轮扫描 | O(m log n) | O(n) | 已接受 |

 ## 算法演练

 我们为每个堆栈维护一个指向其最小未使用值的指针。 由于除了排序之外，堆栈内的值无关紧要，因此在获取值时我们总是前进该指针。 

1. 初始化一个结构，对于每个堆栈，存储其当前最小的未使用的卡。 这些形成了一个以价值为关键的全球候选人库。 
2. 虽然有可能形成新一轮，但我们尝试构建新一轮。 
3. 为了构建一轮，我们按照价值递增的顺序扫描候选者。 我们维护一个变量`last_index = 0`。 
4. 当我们遇到候选人时`(value v, stack i)`，只有当`i > last_index`。 如果我们接受，我们会更新`last_index = i`并将这张卡标记为已使用，将该堆栈的指针前进到下一个未使用的值。 
5. 我们继续这个过程，直到收集到`k`牌。 如果我们成功收集`k`卡片，我们完成这一轮并将答案加一。 否则，不可能再进行整轮比赛，我们就会停止。 
6. 除了已由指针维护的新“下一个候选值”之外，所有剩余未使用的值与未来轮次无关。 

微妙的一点是为什么一轮内的贪婪选择是有效的。 我们总是按升序处理值，因此任何由于索引太小而被跳过的选择稍后都不能在不违反递增索引约束的情况下被更好的更小的值替换。 如果有一组有效的`k`如果堆栈存在，贪婪扫描将找到兼容的递增序列，因为它总是首先保留可用的最小可能值，为同一轮中的未来选择留下最大的灵活性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    stacks = []
    total = 0

    # store each stack as list of values
    for _ in range(n):
        arr = list(map(int, input().split()))
        a = arr[0]
        vals = arr[1:]
        stacks.append(vals)
        total += a

    # sort values inside each stack for deterministic "next unused"
    for i in range(n):
        stacks[i].sort()

    ptr = [0] * n

    # we maintain current candidates (value, stack)
    import heapq

    heap = []
    for i in range(n):
        if ptr[i] < len(stacks[i]):
            heapq.heappush(heap, (stacks[i][ptr[i]], i))

    ans = 0

    # helper: rebuild heap top lazily when stack advances
    while True:
        picked = []
        last_idx = 0

        used_this_round = []

        # we need a working copy of heap
        tmp = heap[:]
        heapq.heapify(tmp)

        while tmp and len(picked) < k:
            v, i = heapq.heappop(tmp)

            if i <= last_idx:
                continue

            # accept this card
            picked.append((v, i))
            last_idx = i
            used_this_round.append(i)

        if len(picked) < k:
            break

        ans += 1

        # apply updates: advance pointers for used stacks
        for i in used_this_round:
            ptr[i] += 1
            if ptr[i] < len(stacks[i]):
                heapq.heappush(heap, (stacks[i][ptr[i]], i))

    print(ans)

if __name__ == "__main__":
    solve()
```该实现为每个堆栈保留一个指向其下一个可用值的指针。 堆仅存储这些当前头。 每轮都是通过从堆的临时副本中贪婪地提取来构建的，以便可以在不破坏全局状态的情况下测试可行性。 

一个微妙的点是，我们在测试一轮时不能直接改变主堆，因为提前一轮失败将需要回滚。 相反，我们使用复制的堆来模拟选择，然后仅在回合成功时提交更新。 

索引约束是通过以下方式强制执行的`last_idx`，确保在一轮内，堆栈索引严格按照所选值的顺序增加。

 | 步骤| 候选人出炉 | 最后_idx | 到目前为止已选|

 | 时间 | O(m log n) | 每次激活每张卡最多从堆中压入和弹出一次，并且每次操作花费对数时间 |

 ## 边缘情况

 第一个微妙的情况是，堆栈单独具有许多值，但由于索引限制，它们的最小值无法尽早使用。 该算法处理这个问题是因为它始终尊重`last_idx`在选择过程中，跳过无效候选而不消耗它们。 

另一种情况是堆栈在不同轮次中贡献多个值。 由于每个堆栈仅在使用其当前头时才前进其指针，因此较早未使用的值永远不会干扰后面的回合。 

最后，当`k = n`，每轮必须使用所有堆栈。 该算法仍然有效，因为在每次扫描中，它都会强制所有索引之间形成完整的递增链，并且当少于`k`兼容的头仍然存在。
