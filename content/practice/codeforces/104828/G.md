 ## 解决方案
 ## 问题理解

 我们有一个小战场，最多有七个相同的敌方小兵。 每个小兵一开始都有一个防护罩，可以完全阻挡第一次传入的伤害。 护盾被打破后，小兵有 4 点生命值，只有在再受到四次单独的单点攻击后才会死亡。 因此，每个小兵实际上需要成功命中五次才能将其从游戏中删除。 

咒语卡由数字a描述。 播放时，它会进行独立试验。 每次试验都会随机选择一个当前存活的敌方小兵，并对其造成 1 点伤害。 如果一个小兵失去了护盾，那么第一次伤害不会减少生命值，但会移除护盾。 一旦小兵的生命值为零，它就会消失，并且不再有资格在以后的试验中被选择。 

对于每张卡牌，我们必须计算在所有随机命中后，每个敌方小兵都被杀死的概率。 

重要的结构是随机性随着时间的推移而演变，因为每当小兵死亡时，有效目标集就会缩小。 这使得该过程成为剩余生命值和护盾状态配置上的马尔可夫链。 

就 Minion 数量而言，约束非常小，最多 7 个；就每个查询的步骤数而言，约束适中，最多 400 个，最多 400 个查询。 这立即表明，只要状态空间仅指数依赖于 n 而不是 a，我们就可以在状态数量上做一些昂贵的事情。 

关键的困难在于，概率不是一个简单的多项式事件，因为选择仅在当前活着的小兵之间是一致的，因此随着死亡的发生，概率会动态变化。 

一个经常破坏解决方案的天真的误解是将每次命中视为初始 n 个小兵的独立制服。 这是不正确的，因为一旦小兵死亡，它就会从池中移除。 另一个微妙的边缘情况是所有小​​兵在使用所有命中之前都死亡。 该过程在越来越小的集合上有效地继续，直到它变空； 一旦为空，就不可能再进行有意义的随机选择，但对于完全清除的概率，这不会改变事件定义。 

第二个常见错误是假设只有点击总数才重要。 例如，当 n = 2 且 a = 10 时，仅知道发生 10 次命中是不够的； 我们必须知道它们的确切顺序，因为每次死亡后目标池都会缩小，从而改变未来的概率。 

## 方法

 暴力破解的观点是逐步模拟整个随机过程。 在每一步中，我们都会维护所有小兵的当前健康状况和护盾状态，枚举每个可能的下一个目标，并相应地传播概率。 这在概念上很简单：每个状态最多分为 n 个转换，并且我们将概率乘以 1 乘以活着的小兵的数量。 

这种模拟的正确性是立竿见影的，因为它准确地反映了过程的定义。 问题在于规模。 每张卡需要最多 400 个步骤，每个步骤都会迭代一个状态空间，该状态空间可以增长到七个小兵的所有配置，每个小兵都有六种可能的状态（死亡、屏蔽或未屏蔽，生命值为 1 到 4）。 大约是 6^7，大约 280,000 个状态。 每个步骤的简单动态程序将需要每个查询进行数亿次转换，而将其乘以最多 400 个查询就变得不可行。

关键的观察是，该过程完全由剩余 Minion 的当前配置决定，并且该配置空间足够小，可以被视为 DP 状态空间本身。 我们没有考虑对每张卡进行单独的模拟，而是在所有配置上计算全局转换系统，并运行时间演化 DP，以达到所有卡上的最大 a。 由于所有查询都从相同的初始状态开始，因此我们重用相同的 DP 进程并简单地在不同的时间步读取答案。 

这将问题转化为在有限状态空间上重复应用固定马尔可夫转移算子。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个查询的逐步模拟 | O(m · a · 状态 · n) | O（状态）| 太慢了 |
 | 所有州和时间的全球 DP | O(maxA·状态·n) | O（状态）| 已接受 |

 ## 算法演练

 我们对每个小兵的状况进行独立编码。 每个小兵可以处于六种状态之一：已经死亡，或活着且有护盾且护盾破坏后剩余 1 到 4 点生命值，或活着且护盾完好。 一种方便的表示方法是将每个小兵视为具有从 5 到 1 的剩余“有效击杀”值，0 表示死亡。 初始状态是长度为 n 的向量，其中每个条目为 5。 

然后，我们构建一个动态规划表，其中 dp[t][state] 是 t 命中后处于该精确配置的概率。 

1. 在所有小兵的值为 5 的状态下，以概率 1 初始化 dp[0]。其他所有状态的概率为 0。这反映了确定性的起始板。 
2. 对于从 0 到 maxA − 1 的每个时间步 t，以非零概率迭代所有状态。 
3. 对于每个这样的状态，计算还有多少个 Minion 还活着。 如果一个 Minion 的值大于 0，则它是活着的。 
4. 从该状态开始，通过均匀选择一个活着的 Minion 将其概率质量分配到所有下一个状态。 每个活着的小兵的概率为 1 除以活着的小兵的数量。 
5. 当选择了一个小兵后，将其剩余值减一。 如果它变为零，则被视为从未来目标集中删除。 
6. 将贡献累积到 dp[t + 1] 中。 

将 dp 填充到 maxA 后，参数为 a 的卡的答案就是 dp[a][terminal_state]，其中terminal_state 是所有条目都为零的配置。 

它之所以有效，是因为 DP 状态完全捕获了所有相关历史。 导致相同配置的任何两个历史都会产生相同的未来行为，因为选择仅取决于哪些小兵仍然活着，而不取决于它们如何达到该状态。 这种马尔可夫性质保证了概率质量可以通过状态安全地合并而不会丢失信息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def encode(state):
    # base-6 encoding of vector, each value in [0..5]
    x = 0
    for v in state:
        x = x * 6 + v
    return x

def decode(x, n):
    state = [0] * n
    for i in range(n - 1, -1, -1):
        state[i] = x % 6
        x //= 6
    return state

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    maxA = max(a)

    S = 6 ** n

    dp = [0.0] * S
    ndp = [0.0] * S

    init = (5,) * n
    dp[encode(init)] = 1.0

    terminal_mask = encode((0,) * n)

    for t in range(maxA):
        for i in range(S):
            if dp[i] == 0.0:
                continue

            state = decode(i, n)

            alive = []
            for j in range(n):
                if state[j] > 0:
                    alive.append(j)

            if not alive:
                ndp[i] += dp[i]
                continue

            p = dp[i] / len(alive)

            for j in alive:
                ns = state[:]
                ns[j] -= 1
                ni = encode(ns)
                ndp[ni] += p

        dp, ndp = ndp, [0.0] * S

    for x in a:
        print(f"{dp[terminal_mask]:.12f}")

if __name__ == "__main__":
    solve()
```该代码直接反映了前面描述的状态转换。 最微妙的部分是状态的编码和解码。 由于 n 很小，我们可以安全地以 6 为基数对每个配置进行编码，这使我们能够以平面结构存储 DP 数组。 

另一个微妙的点是处理没有小兵存活的状态。 在这种情况下，概率质量只是停留在终端配置中，因为不可能进行进一步的转换。 

时间步长的外部循环确保我们对所有查询重用中间分布。 

## 工作示例

 考虑一个小情况，其中有一个小兵和一张 a = 5 的卡。状态空间仅包含从 5 到 0 的值。 

| 步骤| 状态| 概率|
 | ---| ---| ---|
 | 0 | [5]| 1 |
 | 1 | [4] | 1 |
 | 2 | [3] | 1 |
 | 3 | [2] | 1 |
 | 4 | [1] | 1 |
 | 5 | [0]| 1 |

 这表明，对于单一目标，该过程变得确定性，因为没有分支。 

现在考虑两个小兵，a = 10。最初两者都为 5。该过程在它们之间随机分配命中，但每当其中一个达到 0 时，所有后续命中都会分配给剩余的一个。 DP 通过根据活着的小兵的数量在每一步分割概率质量来正确地捕获这一点。 

| 步骤| 典型配置| 解读|
 | ---| ---| ---|
 | 0 | (5,5) | 开始 |
 | 3 | (2,5),(3,4),(4,3),(5,2) | 的混合物 两人都还活着|
 | 5 | 状态如 (0,4),(1,3),(2,2) | 一个人可能已经死了|
 | 10 | 10 (0,0) 有一定概率 | 都死了|

 该跟踪显示了当 Minion 死亡时状态空间如何自然收缩，以及为什么仅跟踪计数会失败。

 ## 边缘情况

 一种重要的边缘情况是所有小兵在使用所有步骤之前都死亡。 在像 (0,0,...,0) 这样的状态下，没有活着的目标，因此 DP 转换将概率质量保持在相同的状态。 这正确地模拟了这样一个事实：一旦游戏提前结束，额外的步骤就不会改变结果。 

另一个微妙的情况是当一个随从即将死亡并且在转换后立即变得不可用时。 例如，从状态 (1,5) 开始，击中第一个小兵会导致 (0,5)，并且下一步绝不能再次选择它。 DP 强制执行此操作是因为活着的 Minions 在每个状态都会重新计算，而不是隐式跟踪。 

最后一个微妙的情况是编码和解码的顺序。 如果 6 进制转换在转换之间不一致，则两个不同的状态可能会错误地发生冲突或分歧。 使用固定长度表示可确保每个配置唯一映射到单个整数，从而保持整个 DP 的正确性。
