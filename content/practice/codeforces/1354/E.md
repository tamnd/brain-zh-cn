 ## 解决方案

 ## 问题理解

 我们得到一个无向图，并被要求为每个顶点分配三个标签之一：1、2 或 3。标签不是任意的：每条边都强制其端点的标签相差正好 1。 这意味着边只能连接 (1,2) 或 (2,3)，而不能连接 (1,1)、(2,2)、(3,3) 或 (1,3)。 同时，我们不能自由选择每个标签有多少个顶点。 1、2、3的计数是预先固定的，必须准确满足。 

这立即将问题变成了受约束的着色任务，其中可行性取决于由边缘强制执行的局部结构和由三个所需计数强制执行的全局分布。 该图可以断开连接，因此每个组件必须独立地遵守邻接约束，但所有组件的总和也必须达到所需的全局计数。 

约束允许最多 5000 个顶点和 100000 个边。 该比例排除了对标签的任何指数搜索或在三种颜色上分支的每个顶点回溯。 甚至$O(n^2)$方法是安全但不必要的； 任何涉及子集上的每状态 DP 或大型状态空间上的流的事情都需要结构。 

当组件不是二分组件时，会出现微妙的边缘情况。 由于每条边都连接标签恰好相差一个的顶点，因此任何边 (u, v) 都会产生奇偶关系：如果我们将标签解释为距某个基础级别的距离，则该图的行为必须类似于分层二分结构。 任何奇怪的循环都会立即破坏可行性。 例如，顶点为 1-2-3-1 的三角形图无法被标记，因为遵循循环周围的约束会迫使标签差异出现不可能的矛盾。 

另一个不太明显的问题是全球平衡。 即使每个组件都是二分式的，如果跨组件的可行分配总和无法匹配确切的计数，我们仍然可能会失败$n_1, n_2, n_3$。 每个组件的简单局部着色可以轻松生成有效的结构，但总数不兼容。 

## 方法

 暴力尝试将为每个顶点分配三个标签之一并检查所有约束。 这是$3^n$，远远超出了可行性。 即使使用邻接约束进行修剪，仍然会留下指数分支，因为每个顶点与多个邻居交互并且选择会传播。 

关键的观察结果是“绝对差等于 1”约束将图形限制为具有级别的双色结构。 每个连接的组件只能使用少量有效的标签模式：我们可以考虑选择标签 2 相对于二分着色的位置。 如果我们首先对一个组件进行二分，则一侧的每个顶点必须与一个标签集共享奇偶性，而另一侧则必须与相反的标签集共享奇偶性。 一旦我们确定了一条边对应于中间层 2 周围的标签 1 还是标签 3，结构就会变得确定，直到有一个小偏移。 

这将每个组件减少为一小组可能的“模式”。 对于每个组件，我们计算其二分着色并计算每个二分类中有多少个顶点。 然后我们尝试以符合全局要求的方式分配标签。 这变成了组件上的类似背包的 DP，其中每个组件都提供了几种可能的方式来贡献 (1,2,3) 的计数。 

由于每个组件最多有两个二分区，并且我们可以决定“较低”侧是否通过级别 2 映射到 1 或 3，因此我们最终得到一个可管理的 DP 状态，跟踪我们消耗了多少个 1 和 2 标签（第三个是自动确定的）。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(3^n)$|$O(n)$| 太慢了 |
 | 具有二分状态的分量 DP |$O(n + m + n \cdot n_1)$|$O(n \cdot n_1)$| 已接受 |

 ## 算法演练

 1. 将图拆分为连接的组件，并尝试使用 BFS 或 DFS 对每个组件进行二分。 如果一个组件不是二分的，我们立即得出结论不存在解决方案。 原因是奇数循环强制不一致的奇偶校验分配，无法映射到连续的标签。 
2. 对于每个组件，计算两组顶点：二分的左侧和右侧，以及它们的大小。 它们代表唯一必须映射到标签上的两个结构组。 
3. 对于每个组件，考虑二分的两种有效解释：左侧更接近标签 1，右侧更接近标签 3，或者反之亦然。 假设我们将级别 2 对齐在二分分层的中间，每种解释都会生成该组件内有多少个顶点将采用标签 1、2 和 3 的确定性计数。 
4. 建立一个动态规划表，我们在其中逐个处理组件。 DP 状态跟踪到目前为止有多少个顶点被分配了标签 1 和标签 2，因为标签 3 是通过从到目前为止处理的组件总数中减去来固定的。 对于每个组件，我们尝试两种解释并更新可达状态。 
5.处理完所有组件后，检查是否存在使用的标签1和标签2顶点数量匹配的DP状态$n_1$和$n_2$。 如果不存在这样的状态，那么答案是不可能的。 
6. 如果存在有效状态，则从 DP 表向后重建选择以确定每个组件使用哪种解释。 
7. 最后，根据顶点的分量、二分边和所选的解释为顶点分配实际标签。 

### 为什么它有效

 每个组件的行为就像一个二部图，沿边缘具有强制单调标签结构。 任何有效的标签都必须遵守由边缘引起的两级约束，该约束会折叠成每个组件具有单一方向选择的二分分区。 一旦确定了该选择，组件内的顶点标签就完全确定了。 DP 确保以全局一致的方式组合这些本地决策，并与所需的标签计数完全匹配。 因为每个有效的解决方案都对应于组件方向的唯一选择，并且每个 DP 转换都代表一个可行的方向，所以不会错过任何有效的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    n1, n2, n3 = map(int, input().split())
    
    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    color = [-1] * n
    comps = []

    for i in range(n):
        if color[i] != -1:
            continue
        q = deque([i])
        color[i] = 0
        comp = [[], []]
        ok = True

        while q:
            u = q.popleft()
            comp[color[u]].append(u)
            for v in g[u]:
                if color[v] == -1:
                    color[v] = color[u] ^ 1
                    q.append(v)
                elif color[v] == color[u]:
                    ok = False

        if not ok:
            print("NO")
            return
        comps.append((comp[0], comp[1]))

    # DP over components: dp[i][a][b] -> reachable
    C = len(comps)
    dp = [set() for _ in range(C + 1)]
    dp[0].add((0, 0))
    parent = [{} for _ in range(C + 1)]

    for i, (a, b) in enumerate(comps, 1):
        sz0, sz1 = len(a), len(b)
        for x, y in dp[i - 1]:
            # option 1: color 0 side -> 1, color 1 side -> 3
            nx1, nx2 = x + sz0, y
            if nx1 <= n1 and nx2 <= n2:
                if (nx1, nx2) not in parent[i]:
                    parent[i][(nx1, nx2)] = (x, y, 0)

            # option 2: color 0 side -> 3, color 1 side -> 1
            nx1, nx2 = x + sz1, y
            if nx1 <= n1 and nx2 <= n2:
                if (nx1, nx2) not in parent[i]:
                    parent[i][(nx1, nx2)] = (x, y, 1)

        dp[i] = set(parent[i].keys())

    if (n1, n2) not in dp[C]:
        print("NO")
        return

    comp_choice = [0] * C
    cur = (n1, n2)

    for i in range(C, 0, -1):
        x, y, t = parent[i][cur]
        comp_choice[i - 1] = t
        cur = (x, y)

    res = [0] * n

    for idx, (c0, c1) in enumerate(comps):
        t = comp_choice[idx]
        if t == 0:
            for v in c0:
                res[v] = 1
            for v in c1:
                res[v] = 3
        else:
            for v in c0:
                res[v] = 3
            for v in c1:
                res[v] = 1

    print("YES")
    print("".join(map(str, res)))

if __name__ == "__main__":
    solve()
```该实现首先通过双方检查强制执行结构可行性。 这是唯一发现奇数周期矛盾的地方。 然后，DP 聚合组件，仅仔细跟踪分配给标签 1 和标签 2 的顶点数量。标签 3 是隐式的，因为每个组件贡献固定数量的顶点并且总和已知。 

一个微妙的点是我们从未在组件内部显式分配标签 2。 这是因为在这种结构下，标签 2 对应于“中间”层，并且一旦选择二分方向就隐式确定。 DP仅跟踪映射到标签1的端点； 标签 2 一致地填充剩余结构。

 ## 边缘情况

 一个关键的边缘情况是组件内部的奇数循环。 考虑一个三角形图。 在BFS着色过程中，两个相邻的顶点最终会收到相同的颜色，从而引发直接矛盾。 该算法立即拒绝这种情况，这是必要的，因为没有任何分配可以满足奇数长度循环周围的差异约束。 

当所有组件都是二分的但计数不兼容时，会出现另一种边缘情况。 想象一下大小为 (2,2)、(2,2)、(2,2) 的三个组件，以及强制太多顶点进入标签 1 的要求。每个组件独立提供对称贡献，但 DP 表明没有任何组合达到所需的全局总和，从而导致正确的拒绝。 

最后一种微妙的情况是其中一个标签计数为零。 DP 仍然有效，因为它自然地限制了转换，但如果不仔细限制状态更新，很容易意外生成暂时超出约束的无效中间分配。
