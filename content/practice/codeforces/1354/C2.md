 ## 解决方案
 ## 问题理解

 给定一个正多边形$2n$顶点，所有边都等于1。多边形是凸多边形，我们可以自由旋转它。 我们必须将其放置在一个正方形内，并且可以自由旋转，使得多边形的每个点都位于正方形边界内或正方形边界上。 任务是找到这样一个正方形的最小可能边长。 

虽然输入给出$n$，实际对象是$2n$- 贡。 自从$n$在此版本中为奇数，多边形的边数为偶数，但不能被 4 整除，这打破了简化 C1 的对称性，并使最佳方向变得不那么简单。 

从几何角度来看，这是一个包含问题：我们试图在固定正多边形的所有可能旋转上找到最小的轴对齐边界正方形。 正方形本身也可以旋转，但这种自由度可以被吸收到多边形的旋转中，因此我们实际上是在单个角度参数上进行优化。 

约束条件$n \le 199$意味着每个测试用例最多 200 次评估。 对于多达 200 个测试用例，在恒定或对数时间内评估候选配置的解决方案就足够了，但如果每次评估都很便宜，则任何需要在多个方向上进行密集采样或强力几何的解决方案仍然会通过。 然而，对精细角度步长的简单扫描将需要每个测试用例进行数百万次检查，这是不必要的。 

当最佳方向未与顶点或边对齐时，就会出现微妙的边缘情况。 例如，当$2n = 10$，最佳正方形不与任何多边形边对齐； 相反，当顶点和相对边同时接触正方形边界时，就会发生这种情况。 仅检查“顶点对齐”旋转的简单方法将错过此配置并返回更大的正方形。 

另一种失败模式来自假设对称性将搜索减少到多边形周期的一半。 对于奇数$n$，多边形没有与正方形对称完全对齐，因此错误地减少搜索空间可能会跳过真正的最佳值。 

## 方法

 蛮力的想法是将多边形视为圆上的一组点并尝试所有可能的旋转。 对于每个旋转角度，我们计算旋转顶点的轴对齐边界框，并获取最大宽度或高度，这是该方向所需的正方形边。 通过精细离散化扫描角度使得这在原则上是可行的。 每次评估费用$O(n)$，如果我们采样$K$角度，总复杂度变为$O(nK)$。 要得到$10^{-6}$精确，$K$必须非常大，通常约为$10^6$，这导致$10^8$每个测试用例的操作太慢了。 

关键的观察结果是，旋转多边形沿某个方向的宽度由圆上的支撑点确定。 对于凸多边形，边界正方形由两个正交方向上的极值投影确定。 随着旋转的变化，这些极端情况仅在顶点与边界方向对齐的离散事件时才会切换。 

这将连续优化简化为有限角度区间内的单峰函数。 我们可以二分查找使正方形边长最小的角度。 函数的每次评估都会计算所有顶点的投影，即$O(n)$，对于双精度，收敛所需的迭代次数约为 60 次。 

更深层次的结构是，平方边是两个正弦投影函数的最大值，并且它们的最大值的最小值与相关区间内的单个全局最小值平滑地表现。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力旋转采样 |$O(nK)$|$O(n)$| 太慢了 |
 | 角度二分查找 |$O(n \log \frac{1}{\varepsilon})$|$O(n)$| 已接受 |

 ## 算法演练

 我们代表常规$2n$-gon 在单位外接圆上。 由于所有边都是 1，因此外接圆半径$R$是：$$R = \frac{1}{2\sin(\pi/(2n))}$$我们将顶点放置为：$$(\cos(2\pi k / (2n)) \cdot R, \sin(2\pi k / (2n)) \cdot R)$$1. 修复候选旋转角度$\theta$。 我们将所有顶点旋转$\theta$。 我们这样做的原因是旋转多边形相当于旋转坐标轴。 
2. 计算旋转点的边界框：$$x_{\min}, x_{\max}, y_{\min}, y_{\max}$$所需的正方形边长为：$$s(\theta) = \max(x_{\max} - x_{\min}, y_{\max} - y_{\min})$$这确保了正方形包含整个多边形。 
3. 定义一个返回的函数$s(\theta)$。 该函数连续于$\theta$并且有一个最小值超过$[0, \pi/(2n)]$由于对称性。 
4. 执行三元搜索（或对导数行为进行二分搜索）$\theta$。 我们评估$s(\theta)$每一步都比较相邻点并向最小值移动。 
5. 收敛后，输出最小值。 

### 为什么它有效

 凸多边形在任意方向上的投影宽度由以下线性函数确定$\cos$和$\sin$的旋转角度。 有限多个此类平滑函数的最大值在正多边形的受限对称区间内是分段平滑且单峰的。 这保证了全局最小值的存在，并且在搜索区间内不会出现次要最小值。 因此三元搜索收敛于正确答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import math

def solve_case(n):
    m = 2 * n
    R = 1.0 / (2.0 * math.sin(math.pi / m))

    # precompute base vertices
    pts = []
    for k in range(m):
        ang = 2.0 * math.pi * k / m
        pts.append((math.cos(ang) * R, math.sin(ang) * R))

    def width(theta):
        c = math.cos(theta)
        s = math.sin(theta)

        xmin = ymin = float('inf')
        xmax = ymax = float('-inf')

        for x, y in pts:
            xr = x * c - y * s
            yr = x * s + y * c
            if xr < xmin: xmin = xr
            if xr > xmax: xmax = xr
            if yr < ymin: ymin = yr
            if yr > ymax: ymax = yr

        return max(xmax - xmin, ymax - ymin)

    l, r = 0.0, math.pi / m
    for _ in range(80):
        m1 = (2*l + r) / 3
        m2 = (l + 2*r) / 3
        if width(m1) > width(m2):
            l = m1
        else:
            r = m2

    return width((l + r) / 2)

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        print(f"{solve_case(n):.10f}")

if __name__ == "__main__":
    main()
```该代码首先利用正多边形由其外接半径唯一确定的事实在外接圆上重建多边形。 半径公式来自于将单位边表示为弦。 

这`width`函数计算固定旋转的正方形边长。 它使用标准二维旋转矩阵旋转每个顶点并跟踪两个轴上的极值。 

三元搜索跑完了$[0, \pi/m]$，由于正多边形的对称性，这就足够了。 80 次迭代计数安全地高于所需的数量$10^{-6}$精确。 

一个常见的错误是尝试搜索$[0, 2\pi]$，它将运行时间乘以一个常数，并且还引入了冗余的等效方向。

def run(inp: str) -> str:

    from math import sin, cos, pi

    # simplified inline solver
    import math

    def solve():
        t = int(input())
        out = []
        for _ in range(t):

            m = 2*n
            R = 1.0 / (2.0 * math.sin(math.pi / m))

                xmin = ymin = 1e18
                xmax = ymax = -1e18
                for x,y in pts:

                    yr = x*s + y*c
                    xmin = min(xmin, xr)
                    xmax = max(xmax, xr)
                    ymin = min(ymin, yr)

 ## 边缘情况

 一个重要的边缘情况是最小的多边形尺寸，$n = 3$，其中形状是正六边形。 这里的目标函数相对平滑且单峰，但可能会出现数值精度问题，因为宽度和高度之间的差异在接近最佳值时变小。 该算法通过在每次评估时重新计算完整浮点极值来处理此问题，而不是依赖增量更新，从而避免累积误差。 

另一个边缘情况很大$n = 199$，其中多边形接近圆。 在这种情况下，最佳正方形边收敛于圆的直径。 二分查找仍然有效，因为宽度函数变得非常平坦，但仍然是单峰的。 重复完整地重新计算投影可以防止漂移。 

最后的边缘情况是当最佳方向出现在搜索区间的边界时$[0, \pi/m]$。 因为该函数是对称且周期性的$2\pi/m$，限制在这个区间仍然捕获全局最小值。
