 ## 解决方案
 ## 问题理解

 我们给定了多个测试用例，每个测试用例都是一个仅由字符组成的字符串`1`,`2`， 和`3`。 对于每个字符串，我们需要找到包含三个字符中的每一个至少出现一次的最短连续段（子字符串）。 如果字符串完全缺少任何一位数字，则不可能形成这样的子字符串，答案为零。 

这里的子字符串是字符串的连续切片，因此我们可以选择起始索引和结束索引，并获取其间的所有内容。 目标是最小化该长度，同时仍然确保所有三个符号在其中至少出现一次。 

约束条件总体来说很大：测试用例中所有字符串的总长度最多可达 200,000。 这立即排除了任何显式检查所有子字符串的解决方案。 在最坏的情况下，尝试每对端点的暴力方法将需要每个测试用例 O(n²)，这太慢了。 

当一位或多位数字完全丢失时，就会出现边缘情况。 例如，如果`s = "111111"`，正确的输出是`0`因为没有`2`或者`3`。 同样，如果一个字符串只包含三个数字中的两个，例如`s = "112211"`，没有子串可以满足条件。 

另一个微妙的情况是当有效子字符串从本地结构中不明显时。 例如，在`s = "1212123"`，最佳段可能包括`3`只在接近结尾处出现一次，迫使窗口向后延伸很远。 

## 方法

 暴力方法将检查每个可能的子字符串并检查它是否包含`1`,`2`， 和`3`。 对于每个起始索引`i`，我们将扩展结束索引`j`并跟踪是否存在所有必需的字符。 即使我们增量地保持频率计数，我们仍然在每次测试的最坏情况下检查 O(n²) 个子串，这会导致在最坏情况下进行大约 1010 次操作。 这不能在给定的约束下通过。 

关键的观察是我们不需要独立检查所有子串。 相反，我们只关心覆盖所有三个字符的最短窗口。 这是一个经典的滑动窗口问题：一旦我们固定了左边界，我们就可以移动右边界，直到所有字符都出现，然后尝试从左侧缩小窗口，同时保持有效性。 

问题的结构保证了扩大窗口单调地增加覆盖范围，而缩小窗口只能减少冗余而不会失去有效性，直到违反约束。 这使得两指针技术就足够了。 我们维持频率计数`1`,`2`， 和`3`在当前窗口中并以线性时间调整指针。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每次测试 O(n²) | O(1) | O(1) | 太慢了 |
 | 滑动窗| 每次测试 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们使用两指针滑动窗口独立处理每个测试用例。 

1.初始化两个指针`l = 0`和`r = 0`，和频率阵列`cnt`大小为 4 来跟踪发生的情况`1`,`2`， 和`3`。 我们还保留一个变量`best`初始化为一个大数。 
2. 展开右侧指针`r`逐步添加`s[r]`进入频率数组。 这逐渐建立了一个候选窗口。 
3. 每次展开后，检查当前窗口是否至少包含一位数字。 这个条件相当于`cnt[1] > 0 and cnt[2] > 0 and cnt[3] > 0`。 
4. 满足条件后，尝试通过移动从左侧缩小窗口`l`向前，同时仍然保留所有三个数字。 每个有效的收缩代表一个更好（或相同）的候选答案。 
5. 在这个收缩过程中，用当前的窗口长度更新答案`r - l + 1`每当窗口保持有效时。 
6.当窗口缩小后再次失效时，停止缩小并继续扩大`r`。 
7. 如果没有找到有效的窗口，则返回`0`。 

关键的想法是每次我们搬家时`l`或者`r`，我们在字符串中单调地这样做，因此每个索引最多被处理恒定的次数。 

它的工作原理归结于最小窗口的结构。 对于任何固定的右端点，通过将左边界尽可能向右推，同时保留所有必需的字符，可以获得以该端点结尾的最佳子字符串。 如果我们没有最大程度地缩小，我们将携带不必要的字符，以及以相同结尾的任何较短的有效子字符串`r`会被错过。 既然我们尝试了所有`r`，我们覆盖了最佳子串的所有可能的右边界。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        
        cnt = [0] * 4
        l = 0
        best = 10**9
        
        for r, ch in enumerate(s):
            x = ord(ch) - 48
            cnt[x] += 1
            
            while cnt[1] > 0 and cnt[2] > 0 and cnt[3] > 0:
                best = min(best, r - l + 1)
                cnt[ord(s[l]) - 48] -= 1
                l += 1
        
        if best == 10**9:
            print(0)
        else:
            print(best)

if __name__ == "__main__":
    solve()
```该实现维护一个直接按数字值索引的频率数组，这避免了任何映射开销。 左指针仅在窗口有效时向前移动，保证正确性的同时保持复杂度线性。 

一个微妙的细节是更新`best`收缩之前。 这确保我们在通过移动可能破坏有效性之前记录每个右端点的最小有效窗口`l`。 另一个重要的点是初始化`best`带有哨兵值，因为可能永远找不到有效的子字符串。

 ## 边缘情况

 当字符串完全缺少一位数字时，频率条件永远不会满足，因此算法永远不会进入收缩阶段，并且`best`保持不变。 为了`s = "333333"`，循环仅增加计数`3`，并且没有记录有效窗口，产生输出`0`。 

当有效窗口存在但远大于最小窗口时，算法依赖于积极收缩。 在`s = "12222133333332"`，一旦`3`包含在内，左指针前进直到最后需要出现`1`或者`2`将会丢失，确保右边界的窗口最小。 这保证了不保留冗余前缀，并且在扫描期间发现每个候选最佳子串。
