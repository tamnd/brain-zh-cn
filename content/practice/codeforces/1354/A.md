 ## 解决方案
 ## 问题理解

 我们正在模拟一个非常简单的系统，该系统随着时间的推移在离散的“睡眠周期”中演变。 一个人需要积累至少目标有效睡眠量才能起床。 该过程从第一个闹钟开始，该闹钟在一段初始延迟后响起，每次醒来后，都会重复相同的模式：闹钟重置，时间过去，人再次入睡，在入睡窗口期间，闹钟可能会响，也可能不会响。 

关键的困难是睡眠不是连续的。 每个周期仅将其持续时间的一部分贡献给总睡眠需求，并且根据参数，该过程可能最终积累足够的睡眠或永远循环而没有进展。 

每个测试用例描述四个数字。 首先是所需的总睡眠时间。 第二次是第一个警报响起时。 第三个是每次复位后后续警报之间的固定间隔。 第四是醒来后再次入睡所花费的时间。 

输出是累积有效睡眠首次达到或超过要求的时刻，如果进程从未设法将总睡眠增加到超出界限值，则输出为 -1。 

约束允许最多 1000 个测试用例和最多 10^9 的值。 这立即排除了任何以单位步长甚至每秒推进时间的模拟。 正确的方法必须推理警报事件之间的跳跃，因为该结构在第一次唤醒后是周期性的。 

当入睡时间比闹钟间隔时间长时，就会出现微妙的边缘情况。 在这种情况下，闹钟总是在人入睡之前响起，因此在第一次醒来后就无法获得有效的睡眠。 例如，如果 a = 10、b = 5、c = 2、d = 100，则在时间 5 醒来后，闹钟始终会在任何睡眠累积之前中断。 正确的输出是 -1，因为睡眠的增加永远不会超过第一次唤醒的贡献。 

当第一个警报之后立即满足所需的睡眠时，会发生另一种边缘情况。 例如，a = 1、b = 1、c = 100、d = 100，答案就是 1，因为不需要进一步处理。 

## 方法

 直接模拟从字面上解决问题。 我们跟踪当前时间、累计睡眠并重复模拟闹钟唤醒。 每次唤醒后，我们要么停止，要么模拟另一个周期。 这是正确的，因为它准确地反映了该过程，但当循环数很大时，它会变得很慢。 在最坏的情况下，我们可能会在达到目标或检测到循环之前执行 10^9 次转换。 

关键的观察结果是，在第一次警报之后，系统变得周期性。 每个周期的行为都是相同的：醒来，可能进入睡眠，重置闹钟，然后重复。 唯一的问题是每个周期是否有助于积极的睡眠。 如果没有，该过程永远无法超越第一个周期的贡献，我们立即得出不可能的结论。 否则，每个周期都会贡献固定数量的额外睡眠，因此我们可以使用算术而不是模拟来计算需要多少个周期。 

暴力破解之所以有效，是因为它直接模拟现实，但当循环次数变大时，它就会失败。 通过观察每个周期贡献固定的正增量或零，我们可以将问题简化为每个测试用例的恒定时间计算。

 ## 算法演练

 我们将时间线分成由警报唤醒分隔的阶段。 第一次唤醒发生在时间 b，之后每个周期以固定结构重复。

我们计算每个周期获得的睡眠时间。 在一个周期中，醒来后，人会花 d 时间入睡。 警报在重置后安排 c 个单位。 如果 d 至少为 c，则警报始终会在该周期中的任何睡眠累积之前中断，这意味着除了已经发生的睡眠之外，不会获得额外的睡眠。 在这种情况下，系统无法继续运行，除非第一次唤醒已经满足要求，否则我们立即返回 -1。 

如果 d 小于 c，则在每个周期中，在警报中断之前，该人会成功睡眠 c - d 个有效时间单位。 这成为每个周期的固定增益。 

我们现在计算第一次醒来后的累积睡眠时间。 如果已经达到目标，我们就停在b处。 

否则，我们确定需要多少个完整周期才能达到剩余的睡眠要求。 每个周期贡献一个恒定量，因此我们使用具有上限行为的整数除法来计算所需的周期数。 

最后，我们通过添加 b 加 c 乘以附加警报间隔的数量，将周期计数转换为时间。 

### 为什么它有效

 第一次醒来后的过程是累积睡眠中确定性的线性循环。 每个周期的增量要么为零，这使得序列有界，要么它是正的并且严格单调。 在单调情况下，值以均匀的步长增长，因此它第一次跨越阈值的时间恰好由除法的上限确定。 任何中间状态都不能跳过最佳答案，因为增量是恒定的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c, d = map(int, input().split())

        if b >= a:
            print(b)
            continue

        if c <= d:
            print(-1)
            continue

        gain = c - d

        remaining = a - b

        cycles = (remaining + gain - 1) // gain

        print(b + cycles * c)

solve()
```该解决方案首先检查初始闹钟时间是否已经满足所需的睡眠，在这种情况下不需要模拟。 然后，它会处理入睡时间过长的退化情况，这意味着第一次醒来后没有任何进展。 

核心计算将过程简化为计算需要多少个相同的生产周期。 上限划分确保我们不会低估达到阈值所需的周期数。 

一个常见的实施错误是忘记第一次唤醒在周期开始之前贡献部分进度。 另一个错误是错误地处理了当 d 大于或等于 c 时没有进度的情况，它必须立即返回 -1。 

## 工作示例

 ### 示例 1

 输入：
 a = 10、b = 3、c = 6、d = 4

 我们首先计算第一次唤醒后的初始睡眠。 

| 步骤| 时间 | 睡眠 | 评论 |
 |------|------|--------|---------|
 | 1 | 3 | 3 | 第一个警报 |

 所需的剩余睡眠时间为 7。每个周期贡献 c - d = 2。 

我们计算周期 = ceil(7 / 2) = 4。 

最终时间为 3 + 4 * 6 = 27。 

该跟踪显示系统如何将重复行为压缩为统一的增量。 

### 示例 2

 输入：
 a = 5、b = 9、c = 4、d = 10

 由于达到所需睡眠时间后第一个警报已经发生，因此答案为 9。 

| 步骤| 时间 | 睡眠 | 评论 |
 |------|------|--------|---------|
 | 1 | 9 | 9 | 已经够了 |

 当不需要进一步仿真时，这种情况证实了提前终止逻辑。

 ## 边缘情况

 当第一次报警时已经满足睡眠要求时，算法立即返回，而不进入循环逻辑。 对于输入 a = 5、b = 10、c = 3、d = 2，结果为 10，因为不需要进一步处理。 

当系统唤醒后无法进行时，例如a = 10，b = 5，c = 2，d = 10，条件c <= d触发，算法正确返回-1。 在此跟踪中，在时间 5 第一次唤醒后，每个周期都会重置，而不会添加有效睡眠，因此不变睡眠值保持恒定，并且永远不会达到阈值。
