 ## 解决方案
 ## 问题理解

 我们面临着一系列敌人，每个敌人都有积极的力量。 对于每个查询，扎格洛尔都会从具有一定初始威力的剑开始，并尝试击败尽可能多的敌人。 规则很简单，但有点不寻常：他可以选择与敌人战斗的顺序，但要击败敌人，他当前的剑力必须至少等于该敌人的力量，并且在击败敌人后，他的剑力将永久减少相同的力量。 

每个查询都是独立的，这意味着我们总是以相同的敌人列表和新的初始剑力重新开始。 任务是针对每个查询计算通过选择最佳顺序可以击败的最大敌人数量。 

隐藏在规则中的关键结构是，每次我们拿下一个实力强劲的敌人时$a_i$，我们永久减少预算$a_i$。 这将问题转化为预算过程，其中每个选定的项目都会消耗部分初始功率。 

约束条件（最多$10^5$敌人和$10^5$查询，值高达$10^9$）立即排除任何对排列或子集的每个查询模拟。 任何查询，即使是二次，也太大了，甚至$O(n \log n)$每个查询将是边界。 我们需要一个预处理的想法，允许每个查询在对数时间内得到回答。 

一些边缘情况值得注意。 

如果所有敌人的力量都大于初始力量，则答案为零。 例如，与敌人$[5, 6, 7]$和$x = 3$，没有战斗是可能的。 

如果所有敌人都很小但数量很多，那么贪婪策略可能看起来依赖于顺序。 例如，与$[4, 1, 3]$和$x = 5$，不同的顺序可能看起来会改变结果，但实际上，一旦我们正确解释它，结构就会迫使我们做出一致的最优选择。 

一个更微妙的情况是，尽早挑选一个大型敌人，然后阻止多个较小的敌人。 例如，$[6, 1, 1, 1]$和$x = 7$：首先采摘 6 片叶子，灵活性太小，而先采摘较小的叶子则可以增加总击杀数。 这暗示顺序很重要，但要以一种非常受控的方式。 

## 方法

 暴力解释是尝试敌人的所有子集以及每个子集的所有可能的顺序，模拟给定的排序在幂递减规则下是否有效。 即使我们忽略排列并只检查子集，我们仍然面临$2^n$可能性，并且每次模拟都会花费线性时间。 这是完全不可行的。 

关键的观察是订单实际上在我们的控制之下，我们希望最大限度地增加我们可以“适应”不断减少的预算的项目数量。 每个选定的敌人都会从总可用功率中消耗自己的力量，并且每一步的约束相当于确保我们永远不会超出剩余预算。 

如果我们决定敌人的一个子集，最好的策略就是按照强度递增的顺序与他们战斗。 这避免了早期在大值上浪费功率，并确保可行性仅取决于总和，而不取决于中间波动。 在这种排序下，条件变得简单：选择后$k$敌人，他们的总和不得超过$x$。 

因此，问题归结为选择尽可能多的元素，使得它们的总和最多为$x$。 为了最大化数量，我们应该始终首先采用较小的元素，因为它们贡献的成本较低并且允许容纳更多的元素。 这将问题转化为排序和构建前缀和数组。 

然后每个查询变成：在它们的累积和超过之前我们可以取多少个最小元素$x$，可以使用前缀和上的二分搜索来回答。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集和订单的暴力破解 |$O(n! \cdot n)$或者更糟|$O(n)$| 太慢了|
 | 排序+前缀和+二分查找 |$O(n \log n + q \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 按非降序对敌人实力数组进行排序。 这确保我们始终首先考虑最便宜的敌人，这对于最大化数量至关重要。 
2. 构建一个前缀总和数组，其中每个位置存储截至该索引的所有敌人的总强度。 这让我们可以快速计算消灭任意数量最弱敌人的成本。 
3. 对于每个具有初始功率的查询$x$，对前缀和数组进行二分查找，找到最大索引$k$使得第一个的总和$k$敌人最多是$x$。 
4. 输出$k$作为该查询的答案，因为它代表在不超过可用力量的情况下可以击败的最大敌人数量。 

二分搜索在这里起作用的原因是前缀和严格增加，因此可行性从 true 到 false 的转换恰好一次。 

### 为什么它有效

 一旦我们确定了要消灭的敌人数量，任何有效的命令都必须遵守剩余力量永远不会低于下一个选定敌人的约束。 按升序排序可确保最难的约束始终最后满足，因为每个步骤在该阶段消耗尽可能小的可用成本。 这会将顺序条件折叠为单个全局条件：所选元素的总和不得超过起始功率。 因为所有值都是正数，所以与首先选择最小可用元素的任何偏差只会减少我们可以容纳的项目数量，而永远不会增加它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
a.sort()

# prefix sums
pref = [0] * n
pref[0] = a[0]
for i in range(1, n):
    pref[i] = pref[i - 1] + a[i]

q = int(input())
out = []

def upper_bound(x):
    lo, hi = 0, n - 1
    ans = -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if pref[mid] <= x:
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1
    return ans + 1

for _ in range(q):
    x = int(input())
    out.append(str(upper_bound(x)))

print("\n".join(out))
```该代码首先对数组进行排序，以便在更强​​的敌人之前考虑较弱的敌人。 前缀和数组转换为“我可以带走 k 个敌人吗？” 进行单一比较$x$。 二分查找找到最大的有效前缀，返回索引加一将其转换为计数。 

一个常见的实现陷阱是忘记答案是计数，而不是索引。 另一个是错误处理即使是最小的元素也太大的情况，在这种情况下，函数通过$-1 + 1$调整。

 ## 边缘情况

 当所有元素超过查询能力时，前缀和数组从上面开始$x$，二分查找正确返回$-1$，转换为零。 例如，与$[10, 20]$和$x = 5$，搜索永远找不到有效的前缀。 

当数组包含许多小元素后跟一个大离群值时，例如$[1, 1, 1, 1, 100]$，对于小查询，算法自然会忽略大元素，因为它在排序后放置在末尾，并且仅与足够大的元素相关$x$。 

什么时候$x$非常大，二分查找总是返回$n$，并且该算法可以正确计算所有元素，而不会出现溢出问题，因为前缀和使用 Python 整数。
