 ## 解决方案
 ## 问题理解

 该字符串仅包含圆括号。 我们需要删除一些字符，同时保持剩余索引的原始顺序。 目标是获得其反转是正则括号序列的最长子序列。 如果没有非空子序列满足这个属性，我们打印`-1`。 

规则的括号序列有两个要求：左括号和右括号的总数相等，并且从左向右阅读时，左括号的数量永远不会小于右括号的数量。 对于反转的常规括号序列，这些条件在反转所选子序列后适用。 

如果选择的子序列是`T`，然后阅读`T`从右到左的行为必须类似于常规的括号序列。 这意味着扫描时`T`从末尾到开头，每个右括号都必须有一个较早的左括号（按相反的顺序）。 

输入的长度可以达到一百万个字符。 尝试不同子序列的解决方案是不可能的，因为可能的子序列的数量是指数级的。 即使检查所有位置对也已经太慢了。 输入大小告诉我们，我们需要一种线性或接近线性的方法，其中每个括号仅处理恒定的次数。 

棘手的情况来自于将普通的正则括号序列与反向括号序列混淆。 例如：```
()
```正确的输出是：```
-1
```整个字符串是规则的，但是反转后就变成了`)(`，这是无效的。 仅检查原始字符串是否包含平衡子序列的解决方案将错误地返回`2`。 

另一种情况是：```
)(
```正确的输出是：```
2
```字符串本身不是规则的，但将其反转可以得到`()`，这是有效的。 检查原始方向的解决方案会错误地拒绝它。 

第三种情况是：```
(((
```正确的输出是：```
-1
```没有足够的右括号来创建一对。 仅计算左括号的数量是不够的； 答案必须包含完整的匹配对。 

## 方法

 一种直接的方法是生成候选子序列并测试它们的反转是否是规则的。 这是正确的，因为它会检查已删除字符的所有可能选择，因此必须出现最佳有效选择。 然而，长度为一百万的字符串有大量的子序列，特别是多达$2^n$，使得这种方法无法使用。 

更好的方法是以不同的方式看待相反的情况。 想象一下从右向左读取原始字符串，而不是构造反向子序列。 所选字符必须在该方向形成正常的规则括号序列。 

对于普通的正则括号子序列，贪心匹配策略就足够了。 当我们看到一个左括号时，它可以等待未来的右括号。 当我们看到一个右括号时，如果可能的话，我们应该使用一个等待的左括号。 每场成功的比赛都会产生一对。 

在向后遍历原始字符串时应用相同的想法给出反向正则括号子序列的最大对数。 我们不需要知道实际选择的指数。 我们只需要匹配对的数量，因为每对都贡献两个字符。 

蛮力之所以有效，是因为它会探索所有可能的删除，但它会多次重复相同的匹配决策。 贪心观察通过证明只要可能匹配就应该使用每个可用的括号来消除重复。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从字符串的末尾开始，向开头移动。 我们沿着这个方向扫描，因为反向选择的子序列必须是规则的。 
2. 维护一个计数器，表示在本次反向遍历中有多少个不匹配的左括号可用。 当我们遇到`(`，增加这个计数器，因为这个括号可以匹配稍后的`)`以相反的顺序。 
3.当我们遇到`)`,检查是否有可用的不匹配的`(`。 如果有，则消耗一个左括号并增加匹配对的数量。 这是该右括号可以形成有效子序列的唯一方法。 
4. 处理整个字符串后，将匹配对的数量乘以 2。 如果没有匹配对，则输出`-1`因为不存在有效的子序列。 

为什么它有效：

 在从右到左的扫描过程中，计数器的含义正是仍然可以支持未来以相反顺序匹配的左括号的数量。 每次计算结束括号时，我们都会将其与一个可用的开始括号进行匹配。 这是最佳的，因为不使用可用的左括号不会比立即使用它对任何以后的右括号更有帮助。 该过程与在反转字符串中查找最长的正则括号子序列相同，因此创建的对的数量是最大可能的。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    s = input().strip()

    available_open = 0
    pairs = 0

    for ch in reversed(s):
        if ch == '(':
            available_open += 1
        else:
            if available_open > 0:
                available_open -= 1
                pairs += 1

    if pairs == 0:
        print(-1)
    else:
        print(pairs * 2)

if __name__ == "__main__":
    solve()
```扫描使用`reversed(s)`以便迭代顺序与反向括号定义所需的方向匹配。 变量`available_open`是该方向已出现但尚未配对的左括号的数量。 

当一个`)`出现后，代码检查边界条件`available_open > 0`减去之前。 如果没有此检查，实现将计算不存在的无效对。 

答案以多对形式存储，因为每场成功的匹配都恰好贡献一个左括号和一个右括号。 最后乘以 2 将对转换为子序列长度。 

不会创建递归、数组或额外的字符串，这一点很重要，因为输入大小可以达到一百万个字符。

 ## 边缘情况

 对于输入：```
()
```该算法从零个可用的左括号开始。 第一个处理的字符是`)`，无法匹配，因此被忽略。 决赛`(`增加计数器，但没有左括号。 对数仍然为零，答案是`-1`。 

对于输入：```
)(
```第一个处理的字符是`(`，这样就可以使用一个左括号。 下一个处理的字符是`)`并消耗该左括号，创建一对。 结果是`2`，这是正确的，因为反转所选序列给出`()`。 

对于输入：```
(((
```每个角色只会增加`available_open`。 没有出现右括号，因此不会创建任何对。 算法输出`-1`，正确拒绝反转后无法平衡的子序列。 

对于输入：```
()()()
```该算法在向后扫描时找到两个匹配项。 它不使用最后一个不匹配的左括号，因为它后面没有可用的右括号。 最终答案仍然是最大可能的长度，`4`。
