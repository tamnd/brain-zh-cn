 ## 解决方案
 # 问题理解

 该问题描述了一排盒子。 有些盒子里有穆罕默德，代表为`1`，而空框表示为`0`。 穆罕默德想要选择一个盒子作为最终集合点，并将当前位于另一个盒子中的每个穆罕默德移动到该所选盒子。 将穆罕默德从一个盒子移动到相邻盒子需要一次交换，因此移动距离`d`盒子成本`d`运营。 任务是找到所有可能的目标框所需的最小交换次数。 

输入包含框的数量和描述其当前状态的二进制字符串。 输出是尽可能小的总移动成本。 

这些约束旨在排除检查每个目的地并重复模拟运动的情况。 如果有`n`盒子和`n`可能很大，尝试每个目的地并扫描整个字符串的解决方案将需要`O(n^2)`操作，速度太慢。 我们需要一种方法，其中每个框仅被处理恒定次数。 

主要的边缘情况来自没有穆罕默德的位置以及所有穆罕默德都已经在一起的行。 粗心的实现可能会假设目的地必须包含 Mohamed，但最佳目的地可能是一个空盒子。 

例如：```
5
00100
```正确的输出是：```
0
```选择已经包含穆罕默德的中间框不需要移动。 仅检查空位置或仅考虑移动到边缘的方法将会失败。 

另一个例子：```
6
100001
```正确的输出是：```
5
```选择任何中间的盒子都会产生更大的成本，而选择任一端点都会移动一个穆罕默德的五个盒子，而将另一个盒子留在原处。 只计算穆罕默德的数量而不计算距离的天真方法会错过实际成本。 

## 方法

 一个简单的解决方案是尝试所有可能的目标框。 对于选定的目的地`i`，扫描整个字符串，每当一个盒子包含 Mohamed 时，添加该盒子与`i`。 这是正确的，因为到达目的地所需的总功正是所有单独运动的总和。 

然而，对每个目的地执行此操作会多次重复几乎相同的计算。 和`n`可能的目的地和`n`要扫描每个框，最坏的情况是`O(n^2)`运营。 对于大行来说，这很快就变得不可能。 

关键的观察结果是相邻目的地是相关的。 如果我们知道将每个人都放在盒子里的总成本`i`，我们可以推导出盒子的成本`i + 1`无需再次扫描整行。 

当我们将目的地向右移动一步时，左侧的每个穆罕默德都会远离一步，而右侧的每个穆罕默德都会靠近一步。 如果我们维持每一方穆罕默德的数量，成本就会发生简单的差异。 这让我们可以在线性时间内计算所有目的地。 

蛮力方法之所以有效，是因为每个可能的目的地都会被准确评估，但它会浪费时间重新计算重叠距离。 对相邻目的地之间的成本如何变化的观察将问题简化为前缀和后缀计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.当目的地是第一个盒子时，计算所有Mohamed的贡献。 

对于每一位处于该位置的穆罕默德`i`，其成本为`i`因为它必须移动`i`框到达第一个位置。 将这些值相加即可得出第一个目的地的初始答案。 
2. 存储该初始成本并准备将目的地从左向右移动。 

在转移目的地时，我们只需要知道当前左右两侧有多少个穆罕默德即可。 
3. 将目的地一次向右移动一个位置。 

假设目的地从位置移动`i`到`i + 1`。 每个穆罕默德都在岗位上`0`通过`i`距离变远了一步，成本增加了左边穆罕默德的数量。 每一个穆罕默德之后`i`靠近了一步，将成本减少了右边穆罕默德的数量。 
4. 使用该差异更新当前成本并保留所见的最小值。 

由于每个可能的目的地都恰好到达一次，因此最小的记录值就是最佳答案。 

为什么它有效：

 不变的是，在处理目的地之前，存储的成本正是将每个穆罕默德移动到该位置所需的交换次数。 将目的地移动一个位置会使每个单独的距离精确地改变一个，增加或减少取决于穆罕默德所在的一侧。 由于所有贡献都是使用其计数一起更新的，因此每个计算的目标成本都是正确的，因此找到的最小值是真正的最佳值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    total = 0
    ones = 0

    for i, c in enumerate(s):
        if c == '1':
            total += i
            ones += 1

    ans = total

    left = 0
    right = ones

    current = total

    for i in range(n - 1):
        if s[i] == '1':
            left += 1
        right = ones - left

        current += left - right
        ans = min(ans, current)

    print(ans)

if __name__ == "__main__":
    solve()
```如果所选目的地是第一个盒子，则第一个循环计算成本。 穆罕默德在索引`i`准确贡献`i`在这种情况下进行交换。 

变量`left`和`right`从左到右扫描时，保持当前目的地前后有多少个穆罕默德。 当目的地移动一个位置时，`left`小组以一分之差越走越远`right`小组越来越接近，这就是更新的原因`left - right`。 

循环停止于`n - 1`因为在最后一步之后就没有下一个目的地可供评估。 所有算术都使用 Python 整数，因此大的移动总数不会溢出。

 ## 边缘情况

 对于`00100`，该算法以初始成本开始`2`，因为穆罕默德距离第一个盒子有两个位置。 当目的地向右移动时，更新会根据左侧和右侧 Mohamed 之间的差异来更改成本。 当目的地到达中心时，成本变为`0`，将其记录为答案。 

为了`100001`，初始成本为`5`。 将目的地向中间移动会使一个穆罕默德更近，而另一个则更远，距离相同，因此总数仍然存在`5`。 该算法并不假设中间总是更好，并正确返回最小值。 

为了`11111111`，每个盒子里都有穆罕默德。 该算法在没有任何特殊情况的情况下处理这个问题。 每次转变都会根据两侧穆罕默德的平衡来改变成本，并且最小值出现在中心附近，从而产生正确的总移动。 

对于单个盒子，例如`1`，循环不执行任何转换，因为没有相邻目的地。 最初的成本已经是最终的答案，这样就避免了相差一分的错误。
