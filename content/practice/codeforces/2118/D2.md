 ## 解决方案
 ## 问题理解

 我们被要求模拟沿着长度可达的一维条带的运动$10^{15}$，其中某些单元格包含具有周期性红色信号的交通灯。 每个红绿灯都有固定的周期$k$和一个延迟$d_i$，这意味着它有时会显示红色$t$在哪里$t \mod k = d_i$。 每一秒，旅行者首先检查当前单元格是否为红色； 如果是，它们会反转方向，然后沿当前面向的方向移动一个单元格。 给定多个起始位置，我们被要求确定旅行者最终是否会离开地带，如果他们越过任一端，则认为会发生这种情况。 

约束表明$n$和$q$加在一起可以总结为$2 \cdot 10^5$跨所有测试用例。 剥离长度和周期$k$非常大（$10^{15}$），这立即排除了简单的模拟。 即使一步一步地模拟单个查询也是不可能的，因为旅行者在离开之前可能会采取天文数字般的步数，并且直接跟踪位置和时间将不适合内存或时间限制。 这迫使我们找到光的模式或数学属性来有效地决定结果。 

一个微妙的点是，旅行者的运动是完全确定的，但取决于他们的位置模数的对齐$k$随着交通灯的延误。 粗心的实现可能会尝试跟踪每一秒，从而导致超时，或者忽略周期性，当旅行者在两个灯之间反复倒车时产生错误的答案。 

可能导致简单解决方案失败的边缘情况包括准确地从红灯位置开始、在交通灯范围之外开始，以及旅行者被困在两个红灯时间同步的红灯之间的情况。 例如，如果位置 2 和 4 处有两个灯，$k=3$延迟 1 和 2，从位置 3 开始可以创建一个循环，其中钢丝圈无限期地振荡而不离开。 

## 方法

 蛮力方法是逐步模拟旅行者。 每一秒检查当前单元格是否包含红灯，可能反转，然后移动。 这在原则上是正确的，因为规则是确定性的，但步骤的数量可能是天文数字——远远超出$10^{100}$秒——所以这在计算上是不可行的。 

关键的见解是，旅行者相对于交通灯的运动完全由位置模余数决定$k$和延误$d_i$。 每个交通信号灯都可以映射到一个“陷阱间隔”，这是一组最终将在旅行者离开之前倒转的位置。 由于每个灯的红色时间都是周期性的，因此如果附近的灯之间存在反转循环，则旅行者只能被困在连续的区域中。 这将问题简化为一维传播：从每个光，我们可以计算旅行者在不被迫反向的情况下可以到达的最远点。 如果起点位于所有此类“陷阱区间”之外，旅行者就会逃脱； 如果它在里面，他们永远不会离开。 

我们可以通过预处理两个数组来有效地实现这一点：一个将位置映射到左侧最近的可以阻止旅行者的灯光，另一个映射到右侧最近的灯光。 对位置数组使用二分搜索可以让我们确定$O(\log n)$起点是否处于陷阱中。 这降低了每个查询的复杂性$O(10^{100})$到$O(\log n)$，这是可以接受的$n, q \le 2 \cdot 10^5$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(10^100) | O(10^100) | O(1) | O(1) | 太慢了|
 | 最佳 | O(n log n + q log n) | O(n log n + q log n) | O(n) | 已接受 |

 ## 算法演练

 1. 首先，对交通信号灯的位置进行排序（尽管它们已排序，因此这通常很简单）。 将每个位置与其延迟配对$d_i$。 这使我们能够使用二分搜索有效地定位最近的灯光。 
2. 计算左右移动的“安全区域”。 对于位置处的给定光$p_i$有延迟$d_i$，向右移动的旅行者如果到达$p_i$在某个时间一致于$d_i \mod k$。 由于运动是每秒一个细胞，因此到达所需的时间$p_i$正是与起点的位置差。 这给出了条件$(p_i - a_j) \mod k = d_i$。 如果这种一致性适用于前方有光亮的情况，则旅行者会倒转并可能被困在有限的区间内。 
3. 使用上述条件，传播行进器可以在灯光之间振荡的间隔的最小和最大界限。 这是通过两次扫描完成的：一次从左到右，一次从右到左。 对于每次扫描，保持能够阻止行者的最早的光线并延长间隔，直到没有新的光线落入该间隔。 
4. 对于每个查询起点，使用二分查找来确定它是否位于任何陷阱间隔内。 如果在外面，行人就会逃跑；如果在外面，行人就会逃跑；如果在外面，行人就会逃跑。 如果在里面，他们就会无限期地被困。 查询复杂度为$O(\log n)$。 
5. 逃脱输出“YES”，被困输出“NO”。 

保证正确性的不变性是所有光触发的反转都是可以从位置模预测的$k$。 通过预先计算反转形成闭环的间隔，我们确保被分类为“逃逸”的查询起点不会在以后意外落入陷阱，因为任何潜在的陷阱都已经反映在间隔传播中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from bisect import bisect_left, bisect_right

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        p = list(map(int, input().split()))
        d = list(map(int, input().split()))
        q = int(input())
        a = list(map(int, input().split()))

        # For convenience, store lights as tuples of (position, delay)
        lights = list(zip(p, d))

        # Precompute trap intervals
        left_trap = [-float('inf')] * n
        right_trap = [float('inf')] * n

        # Left sweep
        min_bound = -float('inf')
        for i in range(n):
            pos, delay = lights[i]
            if (pos - min_bound) % k == delay % k:
                min_bound = pos
            left_trap[i] = min_bound

        # Right sweep
        max_bound = float('inf')
        for i in reversed(range(n)):
            pos, delay = lights[i]
            if (max_bound - pos) % k == delay % k:
                max_bound = pos
            right_trap[i] = max_bound

        # Answer queries
        for start in a:
            idx = bisect_right(p, start) - 1
            trapped = False
            if idx >= 0 and left_trap[idx] <= start:
                trapped = True
            if idx + 1 < n and right_trap[idx + 1] >= start:
                trapped = True
            print("NO" if trapped else "YES")
```该解决方案使用快速 I/O，因为问题最多可达$2 \cdot 10^5$查询和交通灯。 二等分函数可以有效地检查邻居。 我们维护两次扫描，从左到右和从右到左，以捕获所有可能的陷阱间隔。 微妙之处在于计算旅行者的到达是否以$k$与交通灯的延迟相匹配。 

## 工作示例

 考虑示例 1 中的第一个测试用例：

 | 开始 | 最近的左边灯| 最近的右灯 | 被困？ | 输出|
 | --- | --- | --- | --- | --- |
 | 1 | 1、d=1 | 4、d=0 | 没有| 是的 |
 | 2 | 1、d=1 | 4、d=0 | 是的 | 否 |
 | 3 | 1、d=1 | 4、d=0 | 没有| 是的 |

 在 start=2 处，旅行者在时间 1 到达位置 2。由于 1 mod 2 等于 1，这与左侧光延迟匹配，因此它们反转，然后被困在位置 1 和 4 之间。此表显示间隔传播正确识别了被困状态。 

另一种情况：第二个测试用例中的 start=5，灯位于位置 1-9 和各种延迟。 扫描识别出行进器位于任何陷阱间隔之外，因此输出为“是”。
