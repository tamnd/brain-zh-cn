 ## 解决方案
 ## 问题理解

 我们被要求在标记为 1 到 n 的顶点上构造一棵有根树，其中 1 固定为根。 树的结构受到严格限制：每条边都必须从较小的标签到较大的标签，因此标签沿着从根开始的任何路径严格增加。 此外，每个节点 i 对其可以拥有的子节点数量都有硬性限制，最多为 i。 最后，顶点按深度分组，每个深度级别必须由连续的标签块组成。 

目标不是显式地构造树，而是确定最深层（距根最远的节点集）的最大可能大小。 

约束非常大，n 高达 10^12，因此任何解决方案都必须避免节点上的显式构造或迭代。 n 中的任何线性甚至对数都可以，但任何依赖于每个节点模拟的东西都是不可能的。 

思考这个问题的一种天真的方法是实际尝试逐个构建级别，为每个深度分配连续的标签，并检查节点的容量限制是否允许我们“支持”下一个级别。 然而，这很快就会变得脆弱，因为一个级别的可行性取决于累积容量，而局部贪婪选择可能会破坏全局可行性。 

当 n 很小时但容量已经紧张时，会出现微妙的边缘情况。 例如，如果 n = 3，则节点 1 只能有一个子节点，节点 2 可以有两个子节点，但标签约束强制严格排序。 过早地尝试将级别设置得太宽可能会阻碍将剩余节点放置得更深的能力，从而导致最后一层的最大化不正确。 

真正的困难在于“级别连续性”和“增加标签”强烈限制了树的形状，有效地将问题转化为全局容量检查而不是组合树搜索。 

## 方法

 如果我们忽略约束并尝试暴力，我们将枚举满足递增标签条件的所有可能的有根树，检查每个节点是否遵守其度数限制，验证级别连续性并跟踪最深级别大小。 有根树的数量呈超指数增长，甚至限制增加标签的树也会带来类似加泰罗尼亚语的可能性爆炸。 这种方法在 n 很小的情况下是完全不可行的。 

关键的观察结果是，约束所强加的结构使得级别的确切形状不如总容量那么重要。 每个节点 i 最多贡献 i 个传出边。 由于树中的每条边都是父子关系，因此任何有效树中的边总数恰好为 n - 1，并且这些边必须由除最后一级节点（没有子节点）之外的所有节点的组合容量支持。 

“每层连续”约束确保我们有效地将区间 [1, n] 切割成连续的段，但它并没有改变边缘受到总可用容量全局限制的事实。 这将问题简化为找到多少个最小标签足以“托管”所有所需的边缘，而将其余的边缘保留为最深层。 

因此，我们不是显式地构建树，而是确定最小前缀 [1..s]，以便这些节点的总容量足以支持所有 n - 1 条边。 一旦前缀固定，所有剩余节点自然形成最后一层，大小为 n - s。

 ## 算法演练

 问题归结为确定需要多少个最小标记节点来“承载”树中的所有边。

1. 观察到每个节点 i 最多可以有 i 个子节点，因此集合 S 中节点的可用子节点总数是 S 中标签的总和。这是该集合的总输出容量。 
2. n 个节点上的任何有效树都恰好有 n - 1 条边。 这些边必须分配给父节点，并且任何节点都不能超过其容量。 
3. 因此，如果我们确定最后一层包含从某个点 s + 1 到 n 的节点，那么所有边都必须由 [1..s] 中的节点支持。 最后一层中的节点不贡献出边。 
4. 这就给出了一个必要条件：[1..s] 中的容量总和，即 s(s + 1)/2，必须至少为 n - 1。否则，无法仅使用这些节点来分配所有边。 
5. 我们选择最小的 s，因为我们希望最大化最后一层剩下的节点数，即 n - s。 
6. 因此，最终答案是 n 减去最小整数 s，使得 s(s + 1)/2 ≥ n - 1。 

### 为什么它有效

 关键的不变量是每条边必须由某个节点的一个容量单位来支持，并且节点 i 最多提供 i 个这样的单位。 由于除了通过增加标签强制执行的前缀后缀分割之外，边与级别结构无关，因此可行性仅取决于总可用容量是否至少为所需的 n - 1 条边。 一旦前缀满足此条件，其余节点始终可以排列到有效的最深级别，因为它们只需要显示为叶子。 这使得前缀阈值既必要又充分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    
    # we need smallest s such that s(s+1)/2 >= n-1
    target = n - 1
    
    s = 0
    # we could binary search, but direct sqrt-based logic is enough
    # find minimal s
    lo, hi = 0, int(2 * (10**12) ** 0.5) + 5
    
    while lo < hi:
        mid = (lo + hi) // 2
        if mid * (mid + 1) // 2 >= target:
            hi = mid
        else:
            lo = mid + 1
    s = lo
    
    print(n - s)

if __name__ == "__main__":
    solve()
```该实现使用对不等式 s(s + 1)/2 ≥ n - 1 的二分搜索直接计算最小前缀长度 s。这完全避免了溢出问题，因为 Python 可以安全地处理大整数。 最终答案计算为该前缀之后剩余节点的数量。 

一个微妙的点是我们从来没有显式地构造树或级别。 正确性参数确保一旦前缀中的容量足够，则始终存在有效的排列，因此仅计算 s 就足够了。 

## 工作示例

 ### 示例 1

 考虑 n = 10。我们需要最小的 s，使得 s(s + 1)/2 ≥ 9。

这表明只需要前四个节点来支持所有边，在最深层留下六个节点。

这表明，即使 n 很小，容量约束也会迫使内部结构和叶子之间发生非平凡的分裂。

 ## 边缘情况

 对于 n = 2，该条件只需要一条边，仅节点 1 就已经可以支持它。 最小 s 变为 1，因此最后一层包含单个节点，这是正确的，因为节点 2 没有剩余的结构约束。 

对于非常大的 n，例如 10^12，由于容量和的二次性质，计算出的 s 仅增长到大约 10^6。 该算法仍然执行少量的二分搜索步骤，并且不会发生溢出或精度问题，因为 Python 本身处理大整数。 

s(s + 1)/2 恰好穿过 n - 1 的转变点是唯一的临界边界； 其他一切都确定性地从该阈值开始。
