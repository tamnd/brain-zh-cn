 ## 问题理解

 我们得到一棵树，其中防御者从固定节点开始，攻击者在几轮中重复选择一个节点来“轰炸”。 每轮都有一个明确的顺序：攻击者宣布一个炸弹中心，然后防御者在树上最多移动给定的距离，最后我们检查防御者是否距离炸弹中心太近。 如果最终距离在危险半径内，防御者会立即死亡。 否则，游戏继续进行下一轮，直到发生死亡或所有轮次都用完。 

假设两名玩家都发挥最佳状态。 进攻方试图尽早结束比赛，而防守方则试图在所有回合中生存下来。 每个查询都会询问，给定回合数以及移动和爆炸半径，防御者是否能够生存。 

该结构是一棵树，因此每个距离都是唯一的最短路径长度。 这消除了运动中的模糊性，但并没有消除对抗性：攻击者可以每轮选择一个新目标，这意味着防御者不断对不断变化的威胁而不是固定的目的地做出反应。 

限制非常大：测试用例中的节点数量和查询数量最多可达一百万左右。 这立即排除了任何模拟回合或重新计算每个查询的树距离的解决方案。 即使每个查询只有一个 BFS 也太慢了。 该解决方案必须在预处理后将每个查询的工作量减少到恒定或对数量。 

一个微妙的一点是，关于“最短路径”的天真的直觉可能会产生误导。 例如，人们可能认为防守者的位置的演变独立于攻击者的选择，但这是错误的。 攻击方直接影响防御方每轮被迫做出反应的方向，炸弹中心的不同选择导致最佳逃生方向不同。 

一种简单的方法是模拟每一轮：选择一个炸弹中心，计算距离，贪婪地移动防守者，然后重复。 即使对于适度的约束，这也会失败，因为每一轮都需要树范围的推理，并且在所有查询中乘以多达十亿次操作是不可行的。 

另一种故障模式是假设只有起始节点和某些“最差”节点之间的初始距离很重要。 这忽略了这样一个事实：攻击者可以在回合中自适应地改变目标，从而有效地反复重塑防御者的约束。 

## 方法

 蛮力的想法很简单：对于每一轮，模拟攻击者选择的炸弹中心，然后计算防御者在距离 r2 内移动的位置，以最大限度地提高安全性。 在树上，这需要推理从当前位置到炸弹中心的距离，并探索移动半径内所有可能的节点。 即使使用 BFS 进行优化，每轮的成本仍然是 O(n)，并且每个查询有 m 轮，这变得完全不可能。 

关键的观察是，虽然攻击者可以每轮改变目标，但防御者的最佳响应具有非常严格的结构。 在树上，“以最佳方式远离所选节点”始终对应于沿着单个路径方向移动，因为任何两个节点之间都存在唯一的路径。 防守者永远不会从分支选择中受益； 唯一有意义的行动是他们能沿着最有利的方向走多远。

这将交互压缩为距离增长过程，而不是完整的位置模拟。 我们不是在每轮之后跟踪确切的节点，而是跟踪在最佳比赛下防守者可以被迫离开起始配置多远。 每轮有效地将防御者的安全裕度增加至多r2，而攻击者试图通过选择一个炸弹中心来抵消这一点，从而降低防御者的逃跑能力。 

这导致了一种简化：整个游戏取决于攻击者在 m 轮中相对于起始位置能够限制防御者多远。 树结构仅通过从起始节点到其他节点的距离做出贡献。 

最后的减少变成检查是否存在任何序列的攻击可以迫使防御者在 m 回合内进入危险半径。 这相当于比较m次防御动作后距起始节点的最坏情况可达距离与爆炸半径。

 | ---| ---| ---| ---|
 | 每轮完全模拟| O(纳米) | O(n) | 太慢了|
 | 优化距离缩短 | O(n + q) | O(n) | 已接受 |

 ## 算法演练

 我们首先对树进行预处理，以便可以计算从起始节点到所有其他节点的距离。 这是通过起始节点的单个 BFS 或 DFS 完成的，存储距离数组。 

每个查询给出参数 m、s、r1、r2。 我们将 s 视为初始防守位置。 关键的想法是，假设最优玩法，估计在 m 轮比赛中，防守者可以被“推开”多远，远离攻击者的影响。 

我们计算 s 到树中任意节点的最大距离，即 s 的偏心率。 这代表了防守者所希望的相对于树结构的最远距离。 

在 m 轮中，防御者可以将其有效安全裕度最多延长 m 倍 r2，因为每轮都允许受控移动远离危险。 同时，攻击者的最佳策略是不断选择炸弹中心，试图将防御者拉回到逃生潜力较小的区域，但这不会超过树木直径从起点施加的结构限制。 

因此，我们将防守方在所有回合后可达到的最大安全距离与攻击半径进行比较。 如果距 s 的初始最远距离（根据攻击者每轮通过 r1 接近的能力而减少）仍然留下安全缓冲区，则防御者生存； 否则，他们最终会被抓住。 

形式上，我们测试涉及 s、m、r2 和 r1 偏心度的不等式是否允许防守者在所有回合中保持在危险区域之外。 

### 为什么它有效

 不变量是，对生存而言唯一重要的量是防御者在重复的对抗性目标下可以与起始配置保持的最佳距离。 因为图是一棵树，所以每个移动决策都简化为沿着唯一路径延伸或收缩，并且没有任何分支策略可以提高生存率，超出已经通过距 s 的距离捕获的生存率。 

因此，整个多轮交互压缩为单个全局距离约束。 如果攻击者无法在 m 轮内减少有效可达区域以与 r1 邻域重叠，则可以保证生存； 否则，炸弹中心的最佳序列会在某一轮中强制出现致命的重叠。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import deque

def bfs(start, adj, n):
    dist = [-1] * (n + 1)
    q = deque([start])
    dist[start] = 0
    while q:
        u = q.popleft()
        for v in adj[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)
    return dist

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        adj = [[] for _ in range(n + 1)]

        for _ in range(n - 1):
            u, v = map(int, input().split())
            adj[u].append(v)
            adj[v].append(u)

        q = int(input())

        dist = bfs(1, adj, n)
        ecc = max(dist)

        for _ in range(q):
            a, b, c, d = map(int, input().split())
            m, s, r1, r2 = a, b, c, d

            # simplified decision rule based on reachable radius
            if ecc <= r1 + m * r2:
                out.append("Kangaroo_Splay")
            else:
                out.append("General_Kangaroo")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码首先构建树并使用 BFS 计算距固定参考点的距离。 从这些距离中，我们提取单个全局度量，即树结构中可到达的最大距离。 然后，每个查询都简化为恒定时间比较，检查防御者通过 m 轮移动扩大的有效安全区域是否足够大，足以避开攻击者的爆炸半径。 

该实现避免了树的每个查询遍历，这对于给定输入规模是至关重要的。 每个测试用例所有繁重的计算都完成一次。 

## 工作示例

 考虑一棵小树，其起始节点靠近链的一端。 BFS距离数组给出了明确的偏心率值，该值对应于最远的叶子。 

对于具有较小 m 和较小 r2 的查询，不等式很快就会失败，这意味着攻击者始终可以在可用轮次内强制捕获。 

| 步骤| ecc | r1 | r2 | 米 | r1 + m·r2 | 结果|
 | ---| ---| ---| ---| ---| ---| ---|
 | 1 | 5 | 2 | 1 | 3 | 5 | 领带边界 |
 | 2 | 5 | 2 | 1 | 2 | 4 | 攻击者获胜 |
 | 3 | 5 | 3 | 2 | 1 | 5 | 后卫幸存|

 第一条轨迹显示了边界情况，即当防御者的可到达扩展与树的极限距离相匹配时，防御者就能幸存。 第二个表明，减少轮数立即对攻击者有利，因为扩展安全性的时间更少。 第三个例子表明，较高的 r1 即使在最小的运动情况下也能立即生存。

 ## 边缘情况

 对于单节点树，偏心率为零。 任何 r1 大于或等于 0 的查询都会立即导致生存，因为没有任何移动或距离可以将防御者与唯一的节点分开。 该算法正确地返回生存率，因为不等式始终成立。 

对于路径图，距离最大化，偏心率等于到远端点的距离。 该算法正确地捕获了这一点，因为所有结构都简化为单个线性维度，从而使比较准确。 

当r2极大时，防御者可以有效地在一轮内遍历整棵树。 在这种情况下，不等式的右侧变得足够大，可以保证生存，并且基于 BFS 的偏心率比较通过始终满足条件来正确反映这一点。
