 ## 解决方案
 ## 问题理解

 该游戏中的每个玩家都保留了一份个人名单，其中列出了如果这些玩家受到审判，他们将投票反对的其他玩家。 投票过程是确定性的：当某个特定玩家被指控时，其他所有玩家都会检查该被指控的玩家是否出现在他们的个人嫌疑人名单中。 如果是的话，他们投票决定取消； 否则，他们就不会。 

如果严格超过半数玩家投票反对，则该玩家将在一轮中被淘汰。 任务是为每个玩家独立确定如果他们是被审判的人是否会被淘汰。 

那么对于每个玩家来说$x$，我们从概念上模拟一个试验，我们计算有多少其他玩家包括$x$在他们的嫌疑人名单中。 如果该计数超过$\frac{n}{2}$， 然后$x$将会被淘汰； 否则他们就能在假设的考验中幸存下来。 

输入结构本质上描述了一种有向关系：每个玩家$i$指出他们会投票反对的一组球员。 问题归结为计算此有向图中每个节点的传入投票，并检查哪些节点的入度严格大于一半$n$。 

这些约束促使我们寻求线性或近线性的解决方案。 所有测试用例中所有可疑列表的总大小受以下限制$4 \cdot 10^5$，这意味着任何处理每条边恒定次数的解决方案都是可以接受的。 然而，每个玩家的任何每次查询模拟都会太慢，因为它会重复扫描所有列表，导致$O(n^2)$最坏情况下的行为。 

当没有玩家达到多数阈值时，就会出现微妙的边缘情况。 例如，如果$n = 4$并且每个玩家最多只被一名其他玩家怀疑，那么阈值严格大于2，所以没有人有资格。 另一个边缘情况是当一名球员被恰好一半的球员怀疑时； 这不能算作淘汰，因为条件严格超过 50%。 

另一个重要的细节是，自投票是不可能通过构造实现的，因此我们永远不需要处理自循环或删除它们。 

## 方法

 对每个候选玩家的直接模拟将像这样工作：对于固定玩家$x$，扫描所有其他玩家的列表并计算有多少个包含$x$。 这是正确的，但价格昂贵。 每次查询的成本$O(\sum k_i)$，并为所有人做这件事$n$玩家导致$O(n \cdot \sum k_i)$，退化为$O(n^2)$在密集的情况下，显然太慢了$n$最多$10^5$。 

关键的观察结果是投票结构在查询之间不会改变。 每个有向边$i \rightarrow a_{ij}$恰好投了一票反对票$a_{ij}$，并且此贡献与当前正在测试的玩家无关。 这意味着我们可以在所有列表的单次遍历中预先计算每个节点的传入边数。 

一旦知道了这些计数，就可以通过检查他们的计数是否超过，在恒定时间内独立评估每个玩家$\lfloor n/2 \rfloor$。 这将问题转化为简单的边缘频率累积问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n \cdot \sum k_i)$|$O(1)$额外 | 太慢了|
 | 最佳|$O(n + \sum k_i)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将问题简化为计算每个玩家在所有可疑列表中被定位的次数，然后按阈值进行过滤。 

1. 创建数组`cnt`尺寸的$n + 1$，初始化为零。 这将存储每个玩家收到的票数。 索引代表玩家，值代表有多少其他玩家投票反对他们。 
2. 迭代每个玩家的嫌疑人列表。 对于每个条目$a_{ij}$, 增量`cnt[a_{ij}]`一个。 此步骤将所有传入的投票聚合到输入结构的单次传递中。 
3. 将消除阈值计算为$\text{limit} = \lfloor n/2 \rfloor$。 仅当玩家的票数严格大于该值时，玩家才会被淘汰。 
4. 迭代所有玩家从 1 到$n$。 对于每个玩家$i$，检查是否`cnt[i] > limit`。 如果是这样，请包括$i$在答案列表中。 
5. 输出答案列表的大小，后跟排序列表本身。 迭代顺序已经保证了排序。 

正确性取决于每张选票独立于被查询的候选人。 投票只是一条向固定端点贡献 +1 的边，淘汰条件仅取决于最终的累计计数。 

### 为什么它有效

 在任何时刻，反对玩家的票数$x$正是指向的有向边的数量$x$。 模拟推杆$x$on Trial 不会改变任何其他结构，因此投票分布在查询之前是固定的。 该算法有效地计算有向图中每个节点的入度，并将其与全局阈值进行比较。 由于每条边仅贡献一次，并且没有边被重复计算或遗漏，因此计算值与每个假设试验中的真实票数相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        cnt = [0] * (n + 1)

        for i in range(1, n + 1):
            parts = list(map(int, input().split()))
            k = parts[0]
            for x in parts[1:]:
                cnt[x] += 1

        limit = n // 2
        ans = []
        for i in range(1, n + 1):
            if cnt[i] > limit:
                ans.append(i)

        print(len(ans))
        if ans:
            print(*ans)

if __name__ == "__main__":
    solve()
```该解决方案读取每个可疑列表一次，然后直接将投票计数聚合到一个数组中。 关键的实现选择是避免任何针对每个玩家的模拟； 相反，每条边都只处理一次。 阈值比较使用整数除法，正确实现了严格的“超过 50%”条件。 

输出是自然排序的，因为玩家是按升序检查的。

 ## 边缘情况

 一个关键的边缘情况是玩家获得恰好一半的选票。 例如，与$n = 6$，如果一名玩家有 3 张来票，则阈值严格大于 3，因此不得将其包括在内。 该算法可以正确处理这个问题，因为它使用`cnt[i] > n // 2`， 不是`>=`。 

另一个边缘情况是一名玩家获得几乎所有选票。 在星形配置中，每个列表都指向玩家 1，`cnt[1] = n - 1`，它总是超过$n/2$为了$n \ge 2$，因此玩家 1 始终包含在内。 计数方法自然地捕获了这一点，无需特殊处理。 

最后一种情况是所有玩家的列表都是空的。 计数器数组在任何地方都保持为零，并且没有索引超过阈值，这与预期的行为相匹配，无需额外的逻辑。
