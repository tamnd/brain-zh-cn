 ## 解决方案
 ## 问题理解

 两个长数字以字符串形式给出，我们可以逐位修改它们，直到它们变得相同。 问题是数字不被视为抽象值，而是被视为由小“破折号”组成的七段显示。 每个数字对应于固定的发光段图案。 

我们可以对各个段执行两种类型的操作。 一个操作从数字中删除一个段，另一个操作向一个数字添加一个段。 每种操作类型都有一个跨这两个数字的全局预算：我们最多可以删除 x 次分段，最多添加 y 次分段。 

任务是确定我们是否可以使用这些有限的段编辑将两个数字转换为相同长度的相同数字字符串。 

输入大小总体而言很小，测试用例的总长度最多为 100。这会立即排除比每个测试用例线性扫描更重的内容。 就复杂性而言，任何独立比较数字的解决方案都足够了。 

将数字差异视为对称会产生一个天真的陷阱。 例如，将一个数字转换为另一个数字并不是一次操作。 一位数字有额外段的不匹配对应于删除，而缺失段对应于添加。 错误地混合这些方向会导致计数错误。 

另一个微妙的情况是假设我们可以在数字之间任意“交换”操作。 事实上，每个细分市场的变化都是针对某个职位的，并且独立地对全球预算做出贡献。 

## 方法

 强力解释将尝试考虑每个数字到其他数字的所有可能转换，并在尊重预算的同时在全球范围内分配操作。 尽管字符串长度很小，但这很快就会变得不必要的复杂性，因为每个位置都是独立的，并且只有段差异很重要。 

关键的观察是我们永远不需要考虑中间数字状态。 每个位置都会产生固定成本：必须删除一些部分，必须添加其他部分。 一旦我们知道了数字 0 到 9 的七段编码，比较两个数字就减少了对不匹配段的计数。 

这将整个问题简化为对所有位置的成本求和并检查所需的总移除和添加是否适合 x 和 y。

 | --- | --- | --- | --- |
 | 蛮力 | 指数超过数字选择| O(n) | 太慢了|
 | 最佳| 每个测试用例 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们依赖于使用七段的固定数字表示。 每个数字都被编码为 7 个位置的位掩码。 

1. 预先计算数字 0 到 9 的段掩码。这定义了每个数字的段。 

这是必要的原因是每个操作都是在段级别而不是数字级别定义的。 
2. 对于每个测试用例，读取两个字符串 s 和 t。 

我们假设它们按位置对齐，因为两者的长度都是 n。 
3. 初始化计数器remove_used = 0 和add_used = 0。 
4. 对于从 0 到 n-1 的每个索引 i，比较数字 s[i] 和 t[i]。 

将两个数字转换为其段掩码。 
5. 计算两个掩码之间的差异。 

每个在 s 中打开但在 t 中关闭的段都有助于删除。 

每个在 s 中关闭但在 t 中打开的段都有助于添加。 
6. 将这些贡献累积到remove_used 和add_used 中。 
7. 处理完所有位置后，检查是否remove_used ≤ x 和add_used ≤ y。 

如果两个条件都成立，则输出YES，否则输出NO。 

### 为什么它有效

每个段都独立于所有其他段，并且每个操作恰好影响一位数字的一个段。 这意味着将一个数字转换为另一个数字的成本完全由其段集的对称差异决定。 将各个职位的这些成本相加可以保持独立性，因此可行性减少为检查所需的总运营是否符合两个全球预算。 

跨位置的重新排列不能减少所需添加或删除的数量，因为每个不匹配都必须恰好修复一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# 7-segment representation for digits 0-9
seg = [
    0b1111110,  # 0
    0b0110000,  # 1
    0b1101101,  # 2
    0b1111001,  # 3
    0b0110011,  # 4
    0b1011011,  # 5
    0b1011111,  # 6
    0b1110000,  # 7
    0b1111111,  # 8
    0b1111011   # 9
]

def solve():
    T = int(input())
    for _ in range(T):
        n, x, y = map(int, input().split())
        s = input().strip()
        t = input().strip()

        rem = 0
        add = 0

        for i in range(n):
            a = seg[int(s[i])]
            b = seg[int(t[i])]

            diff_remove = a & (~b)
            diff_add = (~a) & b

            # count bits
            rem += bin(diff_remove).count("1")
            add += bin(diff_add).count("1")

        if rem <= x and add <= y:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```该解决方案将每个数字编码为固定的位模式，并逐个位置地比较它们。 关键的实现细节是使用位运算将差异分为删除和添加。 对设置的位数进行计数可以得出所需操作的确切数量。 

一个常见的错误是将两个方向合并为一个绝对差值计数。 这将忽略操作在全局范围内受到类型限制的事实。 

## 工作示例

 ### 示例 1

 输入：```
n = 3, x = 2, y = 2
s = 101
t = 111
```我们比较每个数字：

 | 我| s[i] | t[i] | t[i] | 雷姆 | 添加| 总雷姆 | 总添加|
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 1 | 0 | 0 | 0 | 0 |
 | 1 | 0 | 1 | 0 | 2 | 0 | 2 |
 | 2 | 1 | 1 | 0 | 0 | 0 | 2 |

 最终状态显示 add = 2，rem = 0。由于 y = 2，x = 2，因此转换有效。 

这证实，当一个数字与另一个数字相比“缺失”部分时，仅需要添加段。 

### 示例 2

 输入：```
n = 2, x = 1, y = 1
s = 88
t = 00
```每次 8 到 0 转换都会为每个数字删除两个段。 

| 我| s[i] | t[i] | t[i] | 雷姆 | 添加| 总雷姆 | 总添加|
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 8 | 0 | 3 | 0 | 3 | 0 |
 | 1 | 8 | 0 | 3 | 0 | 6 | 0 |

 我们需要删除 6 次，但只有 x = 1，所以答案是否定的。 

这表明每个职位独立贡献并且成本线性累积。

 ## 边缘情况

 一个关键的边缘情况是两个数字相同。 在这种情况下，移除计数和加法计数都必须保持为零，并且算法自然会产生零，因为对称差为空。 例如，将 7 转换为 7 不会产生不同的位，因此两个计数器保持不变。 

另一个边缘情况是最大分歧，例如 8 到 0。8 数字表示所有段都处于活动状态，而 0 则表示除中间段之外的大多数段处于活动状态。 该算法正确地将缺失的段分类为仅删除，并且不计算添加。 

最后一个边缘情况是预算紧张但分配不均。 x 很大但 y 为零的情况会强制任何所需的添加来阻止解决方案，即使总失配很小。 由于我们分别跟踪两个计数器，因此即使总差异看起来很小，检查也会正确拒绝此类情况。
