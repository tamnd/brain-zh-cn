 ## 解决方案
 ## 问题理解

 我们有多个独立的场景，其中一个人拥有固定金额并想要购买已知价格的饮料。 对于每种情况，我们需要确定需要多少额外资金，以便可用金额足以支付成本。 如果当前的资金已经覆盖或超过了价格，那么就不需要借钱。 

每个测试用例包含两个整数。 第一个是当前可用的金额，第二个是饮料的成本。 每种情况的输出都是成本与可用资金之间的差额，但绝不是负数。 

输入大小可以大到 100,000 个测试用例，每个值最多可以达到 100,000 个。 这立即排除了任何在恒定时间之外为每个测试用例执行额外工作的方法。 每个测试用例的任何嵌套循环或模拟都会超出时间限制，因为即使 O(t log t) 在这里也是不必要的开销，而 O(t) 是目标。 

当可用资金已经足够时，关键边缘行为就会发生。 例如，如果 x = 10 且 y = 7，则答案为 0，而不是 -3。 直接打印 y - x 而不保护符号的简单实现会产生不正确的负输出。 另一个微妙的情况是当 x 完全等于 y 时，答案也必须为 0。 

## 方法

 思考这个问题最直接的方法是想象一次重复借一英镑，直到总额达到所需的成本。 如果 x 小于 y，我们需要重复加 1，直到达到相等。 这种强力解释在概念上是正确的，但效率低下：在最坏的情况下，当 x = 0 且 y = 100,000 时，每个测试用例需要 100,000 个步骤，导致在最差的输入大小下进行 10^10 次操作。 

问题的结构消除了任何模拟的需要，因为最终答案仅取决于两个数字之间的差异。 我们可以直接计算确切的赤字，而不是增量借贷。 如果当前金额已经足够，则赤字为零。 否则，它恰好是 y - x。 这一观察将整个过程简化为每个测试用例一次算术比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(t · | y − x | ) |
 | 最佳| O(t) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取测试用例 t 的数量，因为每个用例都是独立的并且可以单独处理。 
2. 对于每个测试用例，读取 (x, y) 对，代表可用资金和所需成本。 
3. 比较x 和y 以确定是否存在赤字。 
4. 如果x大于等于y，则输出0，因为不需要借位，且借位不能为负数。 
5. 否则，输出 y - x，它直接测量达到成本所需的缺失量。 

### 为什么它有效

 对于每个测试用例，结果仅取决于 x 是否覆盖 y。 如果x≥y，则已经满足要求，因此最小附加量为零。 如果 x < y，则任何有效的解决方案都必须将 x 增加到至少 y，并且此类增加的最小值恰好是 y - x。 没有替代组合或隐藏约束，因此这种差异唯一地决定了答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x, y = map(int, input().split())
        if x >= y:
            print(0)
        else:
            print(y - x)

if __name__ == "__main__":
    solve()
```该解决方案使用快速输入读取所有测试用例，以有效处理多达 100,000 行。 每个案例都在恒定时间内独立处理。 条件检查确保我们永远不会输出负值，这是此问题最常见的实现错误。 

仅当 x < y 时才执行 y - x 减法，保证正确性并避免不必要的计算。 这种分离还使逻辑变得明确，并且可以安全地应对相等等边缘情况。

 | ---| ---| ---|

 ## 边缘情况

 一种重要的边缘情况是相等，其中 x 等于 y。 用于输入`10 10`，算法检查`x >= y`直接输出0。这证实了当金额与成本完全匹配时不需要借钱。 

另一种情况是 x 为零时。 为了`0 50`，条件`x >= y`失败并且算法计算`50 - 0 = 50`。 这确保了正确处理丢失的初始资金，无需特殊外壳。 

一个相反的情况就像`100 1`测试是否在所有情况下都不会错误地应用减法。 自从`x >= y`成立时，输出被正确钳位为 0，而不是产生负值。
