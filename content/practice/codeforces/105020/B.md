 ## 解决方案
 ## 问题理解

 我们看到已经在商店里排队的顾客了。 排队中的每位顾客都需要已知的服务时间，商店会严格地逐一处理。 清除队列任何前缀的总时间只是这些服务时间的总和。 

Hendy 有两种方法为每个查询获取食物。 

第一个选择是亲自去商店。 他花费的旅行时间为$x$分钟，然后他加入当前队列的末尾。 由于队列已经有$n$前面有顾客，等所有顾客都结束后，他才会开始接受服务。 他自己的服务时间实际上是无关紧要的，因为我们只会询问他何时收到食物，而关键时刻是他面前的队列被清除时。 因此，该选项的完成时间是他的到达时间加上处理所有现有客户所需的总时间。 

第二种选择是送货。 在这种模式下，商店正好提供第一个服务$m$顾客排队，然后立即消费$y$分钟送达亨迪的订单。 所以他的等待时间只取决于处理第一个需要多长时间$m$客户，加上交货延迟。 

每个查询独立地要求这两种策略中的最小值。 

从约束条件来看，两者$n$和$q$可以达到$10^5$。 为每个查询重新计算队列总和的解决方案将重复最多$10^5$长度总和$10^5$，导致$10^{10}$的操作，远远超出了可接受的范围。 这立即表明前缀和对于使每个查询恒定时间是必要的。 

一个微妙的边缘情况来自于正确解释“去商店”选项。 如果有人错误地认为亨迪可以插队或到达后立即得到服务，他们就会低估时间。 正确的模型是严格的先进先出：他在最后加入并等待所有当前的客户。 

另一个边缘情况是处理$m = n$，其中交付等待整个队列，使得两种策略非常相似。 另外，当$x$或者$y$非常大，根据前缀和，比较可能会严重翻转。 

## 方法

 暴力解决方案将独立模拟每个查询。 对于交付选项，我们将对第一个求和$m$每次服务次数。 对于商店选项，我们将总结所有$n$服务时间并添加$x$。 这在逻辑上是有效的，因为它直接镜像进程，但它变得太慢，因为每个查询可能需要扫描最多$10^5$元素，产生高达$10^{10}$总操作。 

关键的观察结果是队列在查询之间永远不会改变。 服务时间的前缀结构允许我们预先计算一次累积和。 之后，所需的数量、总队列时间和任何前缀总和都变为 O(1) 查找。 这将每个查询减少为两个预先计算值之间的恒定时间比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(1) | O(1) | 太慢了|
 | 前缀和 | O(n + q) | O(n) | 已接受 |

 ## 算法演练

 1. 读取服务时间数组并计算前缀总和数组，其中每个位置存储为达到该索引的所有客户提供服务所需的总时间。 这允许稍后进行恒定时间范围总和查询，因为每个前缀总和都对队列到该点的完整历史记录进行编码。 
2. 计算整个队列的总服务时间作为最后一个前缀和值。 这表示如果 Hendy 加入队列末尾所需的时间。 
3. 对于每个查询，请阅读$x$,$y$， 和$m$。 这些定义了到达商店的行程时间、交货延迟以及交货开始前服务的客户数量。 
4. 计算店铺选择时间为$x + \text{total queue time}$。 这反映了旅行后抵达，然后等待所有当前客户。 
5. 将交货选项时间计算为$\text{prefix}[m] + y$。 这反映了等待第一个$m$客户然后交货延迟。 
6. 输出这两个值中的最小值。 

### 为什么它有效

 该算法依赖于队列处理顺序是固定且独立于查询的不变量。 由于服务时间是累加的并且系统是严格顺序的，因此到达队列中任何点的时间仅取决于前缀和。 每个查询都简化为比较从该固定时间线的不相交片段派生的两个独立线性表达式，确保查询之间的交互不会使预计算无效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]
    
    total = pref[n]
    
    q = int(input())
    out = []
    
    for _ in range(q):
        x, y, m = map(int, input().split())
        
        go_shop = x + total
        delivery = pref[m] + y
        
        out.append(str(min(go_shop, delivery)))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```前缀和数组构建一次，以便无需迭代即可检索任何段和。 变量`total`捕获完整的队列处理时间，该时间可重复用于每个查询。 

每个查询仅执行算术和数组访问，确保恒定时间行为。 

一个常见的实现错误是忘记了在此公式中前缀数组是 1 索引的，其中`pref[i]`代表第一个的总和`i`元素。 这可以避免查询时出现一对一的混乱`pref[m]`。

 ## 边缘情况

 一个重要的情况是当$m = 1$，其中交付仅取决于第一个客户。 前缀和减少为单个元素，索引中的任何差一错误都会立即浮现出来。 该算法通过使用 1 索引前缀数组来处理此问题，其中`pref[1]`始终有效。 

另一种情况是当$n = 1$。 在这里，两种策略几乎是对称的，并且在解释“加入队列”与“立即服务”时的任何错误都会产生不正确的结果。 计算出的总数仍然正确地包括单次服务时间。 

什么时候$x$非常大并且$y$很小，无论队列大小如何，交付都应该占主导地位。 该公式自然地反映了这一点，因为两个表达式都保持线性和独立，确保在没有特殊大小写的情况下正确比较。
