 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 每个场景中都有$n$cookies总数，其中$a$很大。 多妮娅想吃一些饼干，但她必须避免被抓住。 规则是她吃完饼干后，至少$m$饼干必须仍未被吃掉。 

她唯一喜欢吃的饼干是大饼干。 所以她试图最大化$a$她可以移除大饼干，同时仍确保剩余饼干的数量至少为$m$。 

改写一下，她开始于$n$饼干，其中$a$是“有价值的”（大）。 她删除了尽可能多的有价值的饼干，但她无法减少下面的剩余总数量$m$。 问题是有多少大cookie可以被安全删除。 

约束条件$n \le 10^{12}$立即排除任何对 cookie 的模拟。 解决方案必须是每个测试用例的恒定时间，因为最多有$10^5$测试用例。 任何迭代或构建与以下成比例的内容的方法$n$是不可能的。 

出现微妙的边缘情况时$n = m$。 在这种情况下，根本不能吃任何饼干，所以无论什么，答案都必须为零$a$。 另一个边缘情况是当$n - m$大于$a$，意味着有足够的“空间”来吃掉所有大饼干，但仍然满足约束。 

天真的错误就是只想$a$事项及回报$a$，忽略来自的限制$m$。 另一个错误是将条件解释为“完全离开”$m$”而不是“至少$m$”，这会错误地强制平等并降低灵活性。

 例如，如果$n=10, m=3, a=7$，粗心的做法可能会认为7块大饼干都可以吃。 但如果 7 个都吃掉，就只剩下 3 个，这是有效的，所以答案实际上是 7。这说明约束是关于可行性的，而不是严格的配额。 

## 方法

 暴力解释会尝试模拟一张一张地吃饼干，总是更喜欢大饼干，直到所有大饼干都被吃掉或者剩余的数量低于$m$。 从概念上讲，这是可行的：在每一步中，我们都会删除一个大 cookie 并检查剩余的 cookie 是否至少仍然存在$m$。 然而，在最坏的情况下，我们可能会模拟最多$10^{12}$拆除，这远远超出了任何可行的期限。 

关键的观察是该过程不依赖于顺序或随机性。 唯一重要的是在不违反限制的情况下总共可以删除多少个 cookie。 如果我们删除$x$饼干，然后$n - x \ge m$， 所以$x \le n - m$。 这意味着我们可以删除的 cookie 总数上限为$n - m$。 由于我们只想删除大cookie，因此我们实际可以取的数量也受到存在多少大cookie的限制，即$a$。 因此，答案就是可用的大 Cookie 数量与可安全删除的 Cookie 最大数量之间的最小值。 

这将问题简化为直接算术比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n)$每个测试用例|$O(1)$| 太慢了|
 | 最佳|$O(1)$每个测试用例|$O(1)$| 已接受 |

 ## 算法演练

 1. 对于每个测试用例，请阅读$n$,$m$， 和$a$。 这些定义了 cookie 总数、所需的最少剩余 cookie 以及大 cookie 的数量。 
2. 计算在不违反条件的情况下总共可以删除多少个cookie。 因为至少$m$最多必须保留$n - m$饼干总共可以吃。 
3. 将此限制与$a$，因为我们不能吃比现有的更大的饼干。 
4. 输出两者之间较小的值$a$和$n - m$。 

步骤 2 背后的原因是，每吃掉一块饼干，无论它是大还是小，剩余的数量都会减少 1。 因此，约束仅取决于移除的总数，而不取决于它们的类型。 

### 为什么它有效

 任何时候，如果多妮娅吃东西$x$cookies，剩余数量正好是$n - x$。 条件要求$n - x \ge m$，重新排列为$x \le n - m$。 因此，她可以删除的 cookie 总数全局范围为$n - m$。 由于她只对大饼干感兴趣，因此最好的策略始终是将删除的“预算”完全花在大饼干上，直到预算用完或她用完大饼干为止。 这确保了最大化和有效性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, a = map(int, input().split())
        max_remove = n - m
        if max_remove < 0:
            max_remove = 0
        print(min(a, max_remove))

if __name__ == "__main__":
    solve()
```代码独立处理每个测试用例。 关键计算是`n - m`，它表示可以删除的 cookie 的最大数量，同时仍然至少保留$m$在后面。 如果$n < m$，该值变为负值，因此它被钳位为零，因为不允许删除。 

最终的答案是允许的删除预算和可用的大 cookie 数量之间的最小值。 这直接实现了导出的约束，无需任何模拟。

 ## 边缘情况

 当$n = m$，该约束强制零移除，因为任何吃掉的饼干都会违反最低剩余要求。 该算法计算$n - m = 0$，所以最终的答案就变成了$\min(a, 0) = 0$，完全符合要求。 

什么时候$n < m$，在约束允许的情况下，计算值$n - m$是负数。 该实现将其限制为零，这意味着不能吃任何饼干。 这正确地反映了条件已被违反或在任何删除后都无法满足。 

什么时候$a \ge n - m$，限制因素变成了剩余的约束，而不是大cookie的可用性。 算法正确返回$n - m$，确保使用全部允许容量。
