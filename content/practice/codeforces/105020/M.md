 ## 解决方案
 ## 问题理解

 我们被要求确定给定的整数是否$x$可以表示为从某些开始的连续正整数块的总和$l$并结束于$r$。 换句话说，我们想要一段连续的自然数，以便将它们加在一起恰好产生$x$，同时还确保段本身严格位于之前$x$就其端点而言，意味着$r < x$。 

每个测试用例给出一个数字$x$，对于每个我们需要输出任何有效的对$(l, r)$或报告不存在此类段。 

这些限制使得在所有区间上进行暴力破解都是不可能的。 天真的扫描一切$l$和$r$将涉及粗略检查$O(x^2)$每次测试的范围，并且因为$x$可以大到$2 \cdot 10^9$，这是完全不可行的。 如果直接完成，即使迭代所有可能的段长度也太大了。 

一个更微妙的约束是需求$r < x$。 这可以防止诸如取单个数字之类的琐碎构造$x$本身或完全结束于的范围$x$，因此任何解决方案都必须产生嵌入自然数中的真正较小的段。 

边缘情况出现在小值和无法表示为三角差的值周围。 例如，$x = 1$和$x = 2$显然失败，因为最小可能的有效段$1 + 2 = 3$已经超过他们了。 另一个有趣的例子是涉及三角数的表示中的二减一行为，其中整除条件默默地排除了许多值。 

## 方法

 暴力方法将尝试修复$l$然后延伸$r$，保持运行总和，直到它等于或超过$x$。 这会正确枚举所有可能的段，并会找到有效的答案（如果存在）。 然而，对于每个起点，内循环可能会运行到$O(\sqrt{x})$甚至$O(x)$最坏情况下的步骤，当重复最多时，总运行时间远远超出可行的限制$10^3$测试用例。 

关键的观察是连续整数之和形成算术级数，可以写成封闭形式：$$\sum_{i=l}^{r} i = \frac{(l + r)(r - l + 1)}{2}$$我们可以推理有效和的结构，而不是在区间内搜索。 我们正在寻找整数$l, r$这样：$$x = \frac{(l + r)(r - l + 1)}{2}$$设线段的长度为$k = r - l + 1$。 然后：$$x = \frac{k(2l + k - 1)}{2}$$重新排列：$$2x = k(2l + k - 1)$$这意味着我们可以迭代可能的段长度$k$，并检查结果表达式是否产生有效的整数$l$。 如果$l$是正数并且$r = l + k - 1 < x$，我们接受它。 

关键的效率增益是$k$只需要达到$O(\sqrt{x})$， 因为$k(k+1)/2 \le x$限制最大有意义的长度。 这将每个测试用例的问题从二次时间减少到基本上是平方根时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(x)$每次测试|$O(1)$| 太慢了|
 | 最佳（尝试长度$k$) |$O(\sqrt{x})$每次测试|$O(1)$| 已接受 |

 ## 算法演练

 我们专注于将问题转化为对段长度的搜索。 

1. 对于每个测试用例，读取值$x$。 

目标是找到有效的细分或得出不可能性的结论。 
2. 迭代可能的长度$k$，从2开始向上。 

长度 1 是无用的，因为它意味着$l = x$，这违反了$r < x$。 
3. 对于每个$k$，计算重新排列的所需总和公式$l$:$$2x = k(2l + k - 1)$$我们隔离：$$2l = \frac{2x}{k} - (k - 1)$$如果$2x$不能被整除$k$，跳过这个$k$。 
4. 一旦整除性成立，计算$l$并推导出$r = l + k - 1$。 

我们检查一下$l \ge 1$和$r < x$，保证问题约束下的有效性。 
5. 如果找到有效的对，则立即输出。 

由于任何有效答案都可以接受，因此我们不需要进一步搜索。 
6.如果穷尽所有后仍不存在有效对$k$，输出-1。 

### 为什么它有效

 每个有效的解决方案都唯一对应于一对$(k, l)$在哪里$k$是段长度。 通过迭代所有可行的长度并重建$l$从代数上来说，我们不是猜测区间，而是直接求解定义它们的方程。 由于每个候选片段都准确地映射到一个$k$，搜索空间完整，不会遗漏任何有效解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x = int(input())

        found = False

        # try segment length k
        for k in range(2, 2 * 10**6):  # safe upper bound (sqrt(2x))
            num = 2 * x - k * (k - 1)
            if num <= 0:
                break
            if num % (2 * k) != 0:
                continue

            l = num // (2 * k)
            r = l + k - 1

            if l >= 1 and r < x:
                print(l, r)
                found = True
                break

        if not found:
            print(-1)

if __name__ == "__main__":
    solve()
```该代码直接遵循代数约简。 我们迭代可能的段长度并重建起点$l$使用重新排列的求和公式。 当分子变为非正值时的早期中断确保我们不会在已经超过目标总和的长度上浪费时间。 

一个微妙的点是仔细维护整数运算。 表达式`num = 2 * x - k * (k - 1)`必须在除法之前计算以避免精度问题并确保正确的整除性检查。 条件`r < x`强制执行问题的严格边界要求。

def run(inp: str) -> str:

    import sys

    out = []
    for _ in range(t):

 ## 边缘情况

 对于$x = 1$，循环立即找不到有效的$k$因为即使是最小的线段总和$1 + 2 = 3$已经超出目标，因此算法正确输出 -1。 

对于非常小的复合值，例如$x = 5$，算法快速识别$k = 2$给予$[2, 3]$，并验证$r < x$成立，证明边界检查不会意外拒绝有效的短段。 

对于没有算术级数完全适合的大类质数值，每个候选者$k$无法整除，并且由于分子条件为负，循环提前退出，从而确认不可行的情况在没有完全枚举的情况下有效终止。
