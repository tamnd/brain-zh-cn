 ## 解决方案
 ## 问题理解

 每个测试用例都描述了一个有几棵树的公园，其中每棵树都有固定的高度。 Amr 选择一棵树躲在后面。 他是否被抓住仅取决于他的身高与所选树的高度之间的比较。 

规则很简单：只有当 Amr 躲在后面的树比 Amr 本人矮时，Gamal 才能抓住 Amr。 如果树足够高或高度相等，Amr 仍然安全。 

因此，对于每棵树，我们需要独立决定其高度是否严格小于给定值$x$，代表 Amr 的身高。 输出是一系列二元决策，每棵树一个。 

约束允许最多$10^3$测试用例和总共$10^5$树木整体。 这已经告诉我们解决方案必须在恒定时间内处理每个高度。 任何在每个测试用例中多次重新访问元素的方法只有在整体保持线性的情况下才仍然可以通过。 任何二次方，例如将每棵树与其他树进行比较，都远远超出了极限，因为它会达到$10^{10}$最坏情况下的操作。 

主要的边缘情况来自于相等和极端的边界比较：

 如果所有树的高度都等于$x$，没有一个应该算作捕获。 例如，$x = 5$, 高度$[5, 5, 5]$，输出必须是$[0, 0, 0]$。 粗心的实现使用$\leq$如果不进行严格比较，则会错误地将所有内容标记为已捕获。 

如果所有树都短于$x$， 例如$x = 10$, 高度$[1, 2, 9]$，那么每个位置都应该返回$1$。 任何翻转条件的错误都会导致结果完全颠倒。 

如果树包含的值大于$x$，即使它们不相等，这些位置也必须是安全的，这可能会导致仅检查相等性或使用不正确的布尔逻辑的实现出错。 

## 方法

 蛮力的想法是独立处理每棵树。 对于每棵树，我们将其高度与 Amr 的高度进行比较，并确定它是否满足“严格较小”条件。 这已经给出了正确的解决方案，因为一棵树的决策不依赖于任何其他树。 

一个天真的误解是重新计算或扫描每棵树的附加结构，但问题中没有任何内容需要位置之间的交互。 即使对于每棵树来说，与所有其他树进行比较的双循环也是不必要和浪费的。 这会导致$O(n^2)$每个测试用例的行为，在最坏的情况下意味着大约$10^{10}$比较，是完全不可行的。 

关键的观察结果是，这种情况纯粹是局部的。 每个输出仅取决于一次比较$h_i < x$。 这消除了对任何预处理或数据结构的需要。 我们可以一次性处理该数组并立即发出答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了|
 | 最佳|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 每个测试用例都是独立的，因此不需要在它们之间传递任何信息。 
2. 对于每个测试用例，请阅读$n$和$x$，它定义了存在多少棵树和 Amr 的高度。 
3. 读取树的高度列表。 每个值将被检查一次。 
4. 对于每个高度$h_i$,直接与$x$。 如果$h_i < x$，输出 1，否则输出 0。这是有效的，因为问题条件定义了严格的不等式作为 Amr 被捕获的唯一方法。 
5. 在一行中打印测试用例的所有结果以匹配所需的格式。 

### 为什么它有效

 每个决定都是独立的，并且仅基于单个数字是否低于固定阈值$x$。 树之间没有隐藏的交互，因此输出正是应用简单谓词的结果$h_i < x$到每一个元素。 由于每个元素对谓词求值一次，因此位置之间不会发生错误耦合，并且结果必须与问题定义匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out_lines = []

    for _ in range(t):
        n, x = map(int, input().split())
        h = list(map(int, input().split()))

        res = []
        for hi in h:
            if hi < x:
                res.append("1")
            else:
                res.append("0")

        out_lines.append(" ".join(res))

    print("\n".join(out_lines))

if __name__ == "__main__":
    solve()
```该实现完全反映了算法。 每个测试用例都是单独处理的，并且对于每个树高度，我们执行一次比较。 结果以字符串形式累积，以避免重复打印开销，这使得 Python 中的解决方案在严格约束下保持高效。 

这里的一个常见陷阱是不小心使用`<=`而不是`<`，这会错误地将等高的树木标记为已捕获。 另一个微妙的问题是打印每个元素而不是连接结果，这会在以下情况下显着减慢 Python 速度：$n$很大。

 ## 边缘情况

 当每棵树的高度恰好等于$x$，算法将每个比较评估为假，产生一系列零。 对于像这样的输入$x = 5$, 高度$[5, 5, 5]$，每次检查$h_i < x$失败，因此没有位置被标记为已捕获。 

当所有树都严格位于下面时$x$，每次比较都成功。 为了$x = 10$, 高度$[1, 2, 9]$，每次比较都返回 true，并且输出变为全 1。 

当值超过$x$，比较自然地将它们过滤掉，无需特殊处理。 为了$x = 3$, 高度$[4, 5]$，两者都更大，因此更安全，始终产生零。
