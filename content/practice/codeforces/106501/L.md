 ## 解决方案
 ## 问题理解

 我们需要构建一组`n`不同的正整数。 每个选择的值必须保持在以下范围内`1`到`100000`。 条件是，如果我们采用最多 8 个选定数字的任何非空组，则该组的总和必须不是完全平方数。 

输入仅给出集合所需的大小。 输出不是要检查的单个答案，而是任何有效的构造。 

的限制为`n`足够小，以至于无法直接搜索最终集合的所有可能子集。 为了`n = 2862`，大小最多为 8 个的子集数量是巨大的。 甚至`C(2862, 8)`远远超出了可以处理的范围。 然而，数字本身是有限的`100000`，因此最多八个元素的可能总和受下式限制`800000`。 这个范围是我们可以利用的关键资源。 

棘手的部分是，如果贪婪构造仅错误地检查当前数字与之前的数字，那么它很容易失败。 单个坏子集只有在多次添加后才会出现。 例如，如果我们输出：```
3
```输出将无效，因为子集`{3}`有总和`3`，它不是正方形，所以这实际上是有效的。 只查找对的粗心检查器可能会忽略单元素子集的重要性。 另一方面：```
1 8
```无效，因为子集`{8,1}`有总和`9`，一个正方形。 仅根据现有单个值检查新值的方法将无法捕获它。 我们需要跟踪大小不超过 8 的所有子集总和。 

另一个边缘情况是空子集。 不能考虑它，因为它的总和为零，是完全平方数。 如果我们在验证最终答案时不小心包含它，则每个构造都会立即失败。 对于输入：```
1
```正确的输出是任何单个非平方数，例如：```
2
```因为只有包含该数字的子集存在。 

## 方法

 一个自然的蛮力想法是从左到右构建集合，并且在添加新数字之前，尝试已选择的大小最多为 7 的数字的每个子集。 如果这些子集与新数字都不能产生平方和，则我们保留该数字。 

这是正确的，因为每个新的无效子集必须包含新添加的值。 问题是我们要检查的子集的数量。 由于有数千个选定值，可能的七号组数量增长得太快。 最坏的情况需要检查数十亿种组合。 

拯救我们的观察是我们不需要知道哪些元素创建了和，只需要知道和是否可能。 由于最大相关总和是`8 * 100000 = 800000`，我们可以按子集大小存储所有可达子集和。 

适合各种尺寸`k`，维护一个位集，其中位`s`意味着存在一个子集`k`所选元素的总和`s`。 当考虑新值时`x`, 如果没有可达总和则有效`s`尺寸的`k`这样`s + x`是任意一个正方形`k`从零到七。 

Python 整数在这里很有用，因为它们的位可以在 C 中非常快速地移位和组合。更新动态编程状态变成了一些位操作，而不是迭代所有和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(100000 * n^7) | O(100000 * n^7) | O(n) | 太慢了|
 | Bitset 贪婪 | O(100000 * 8 * 800000 / 字大小) | O(8 * 800000) | 已接受 |

 ## 算法演练

 1. 预先计算可以作为子集和出现的每个完美平方。 最大可能的子集和是`800000`，因此所有达到该值的平方就足够了。 
2. 创建八个位集。 索引处的位集`k`代表通过精确选择可获得的所有总和`k`已经选定的号码。 最初仅存在空子集，因此大小为零的位集包含和零。 
3. 迭代候选编号`1`到`100000`。 对于每位候选人`x`，检查添加它是否会创建一个正方形。 对于每个可能的先前子集大小`k`，寻找等于的可达总和`square - x`。 如果存在这样的总和，`x`不能使用。 
4. 如果`x`有效，将其添加到答案中并更新位集。 大小的子集`k`可以成为大小的子集`k + 1`通过添加`x`，这恰好是位集的左移`x`。 
5. 收集完毕后停止`n`数字。 贪心选择之所以有效，是因为每个接受的数字都保留了这样的不变量：所选数字中最多八个大小的子集都不具有平方和。 

为什么它有效：

 维护的位集准确地描述了已选择的数字中每个子集大小的每个可能的子集和。 当我们测试新值时，任何新创建的无效子集必须由新值加上大小最多为 7 的旧子集组成。 检查会检查所有此类可能性。 如果该值被接受，则不会引入新的坏子集，因此更新后不变式仍然为真。 通过归纳，最终的集合满足要求的条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAX_SUM = 800000

squares = []
i = 1
while i * i <= MAX_SUM:
    squares.append(i * i)
    i += 1

def solve():
    n = int(input())
    
    dp = [0] * 9
    dp[0] = 1
    
    ans = []
    
    for x in range(1, 100001):
        ok = True
        
        for k in range(8):
            bits = dp[k]
            for sq in squares:
                need = sq - x
                if need >= 0 and ((bits >> need) & 1):
                    ok = False
                    break
            if not ok:
                break
        
        if ok:
            ans.append(x)
            for k in range(7, -1, -1):
                dp[k + 1] |= dp[k] << x
            
            if len(ans) == n:
                break
    
    print(*ans)

def main():
    solve()

if __name__ == "__main__":
    main()
```方形列表只构建一次，因为仅求和`800000`可能很重要。 更大的正方形永远不能由最多八个允许值的子集产生。 

数组`dp`有九个条目，因为子集的大小可以从零到八。 每个条目中存储的值是用作位集的 Python 整数。 少量`s`被设置意味着总和`s`是可以实现的。 

在验证步骤期间，循环`k`检查所有可能的先前子集大小。 我们只需要大小 0 到 7，因为新值本身贡献了第八个元素。 更新会向后遍历大小，因此当前数字不会在同一更新中多次重复使用。 

不存在整数溢出问题，因为 Python 整数具有任意精度。 所需的最大位位置仅为`800000`，这是可以管理的。

 ## 边缘情况

 对于最小情况`n = 1`，算法拒绝`1`因为它是一个正方形并接受`2`。 子集跟踪仍然有效，因为空子集在内部表示，但从未被视为最终子集。 

对于配对很重要的情况，例如选择`1`和`8`，第二个数字将被拒绝。 添加前`8`，大小一的位集包含总和`1`， 和`1 + 8 = 9`被检测为正方形。 这可以防止仅检查单个值的常见错误。 

对于最大尺寸`n = 2862`，循环继续，直到收集到足够的有效数字。 位集表示避免存储所有可能的子集，因此构造仍然可行。
