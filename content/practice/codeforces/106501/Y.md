 ## 解决方案
 ## 问题理解

 这个问题要求我们尽快安排走访每家商店。 商店数量很少，但随着时间的推移，每个商店都会有许多其他顾客到来。 奥金奈选择商店的顺序，当他到达一家商店时，他可能必须等待已经在队列中的顾客。 每家商店都需要固定的时间来服务任何顾客，包括奥金尼。 

输入给出了商店数量、外部顾客数量、每个商店的购物持续时间以及每个外部顾客的到达时间以及他们访问的商店。 输出是奥金奈完成所有商店的最早时刻。 

商店数量最多为18个。这个小值是主要线索。 尝试每一个可能的订单需要`18!`可能性已经太大了。 子集动态规划解决方案是现实的，因为只有`2^18 = 262144`子集。 外部客户数量可达`200000`，因此模拟每个转换的队列会太慢。 我们需要对每个商店的排队行为进行预处理。 

时间的大值，最多`10^9`，意味着实现必须使用 64 位整数。 Python 整数已经安全地处理了这个问题。 

有少数情况很容易处理不当。 如果奥金奈恰好在另一位顾客到达时到达，则该顾客必须在他之前到达。 例如：```
Input
1 1
5
1 0
```正确的输出是`10`。 一个粗心的实施，只计算到达时间严格小于 Auchenai 到达时间的客户，将使 Auchenai 立即启动并生产`5`。 

另一个棘手的情况是没有顾客等待时。 例如：```
Input
1 0
5
```答案是`5`。 始终查找先前队列完成时间的解决方案可能会意外地增加不必要的延迟。 

最后一个特殊情况是顾客很久以前就到达了，但他们的队列已经空了。 例如，如果一家商店购买 3 件商品，一名顾客在时间 1 到达，那么在时间 10 到达的顾客应该在时间 13 完成，而不是 14。队列历史记录很重要，但仅限于 Auchenai 到达那一刻。 

## 方法

 直接的方法就是尝试每一种可能的逛店顺序。 对于固定订单，我们可以模拟队列并计算最终完成时间。 这是正确的，因为考虑了所有可能的时间表。 问题是时间表的数量。 共有18家店铺`18!`订单，大约是`6.4 * 10^15`，使得暴力破解变得不可能。 

第一个改进是认识到未来并不取决于达到当前情况所使用的确切顺序。 参观完一些商店后，唯一重要的信息是当前时间以及剩余的商店。 这给出了自然子集动态规划状态。 

对于已访问过的商店的子集，我们存储奥金奈可以完成该子集中所有商店的最早时间。 从该状态开始，我们尝试添加每个未访问过的商店。 

剩下的挑战是快速回答这个问题：如果奥金奈到达商店`i`在某个时间`x`，他什么时候完成？ 商店的外部顾客总是按时间顺序到达，他们从不依赖奥金奈的决定。 对于每个商店，我们在第一个商店之后对其外部队列的完成时间进行预处理`k`顾客。 然后二分搜索告诉我们有多少顾客按时间到达`x`，我们立即知道他们的队列清除的时间。 

蛮力之所以有效，是因为每个可能的订单都会被检查，但会失败，因为订单数量激增。 只有访问集和最早完成时间重要的观察结果将问题简化为子集 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(n! * n)`|`O(n)`| 太慢了|
 | 最佳|`O(2^n * n * log m)`|`O(2^n + m)`| 已接受 |

 ## 算法演练

 1.对每个店铺的顾客到达时间进行排序。 对于每个商店，构建一个前缀数组，其中`k`-th 值代表第一次出现的时间`k`外面的顾客已经完全购物完毕。 

前缀值允许我们稍后忽略单个队列模拟。 DP 中的每次转换只需要知道有多少客户已经到达。 
2.创建动态规划数组`dp[mask]`。 有点在`mask`代表 Auchenai 已经访问过的一家商店。 存储的值正是这些商店的最早完成时间。 

初始状态是`dp[0] = 0`因为在访问任何商店之前，当前时间都是零。 
3. 迭代每个子集`mask`。 如果状态可达，则尝试每个未包含在掩码中的商店。 

添加一家商店相当于选择时间表中的下一个目的地。 
4. 选择下一家店铺`i`，设当前时间为`cur = dp[mask]`。 在商店中使用二分搜索`i`的到达列表，查找到达时间最多的外部顾客数量`cur`。 

顾客恰好到达`cur`必须包括在内，因为他们在奥金尼之前进入队列。 
5. 使用这些客户的预先计算的队列完成时间。 奥金奈在他的到达时间和现有队列都结束后开始，然后花费`t[i]`单位购物。 
6. 更新包含新访问的商店的状态。 处理完所有子集后，答案为`dp[(1 << n) - 1]`。 

为什么它有效：

 不变的是`dp[mask]`始终存储访问恰好位于以下商店的所有订单中的最佳完成时间`mask`。 当我们通过访问另一家商店来扩展状态时，我们会计算该选择的确切结束时间，因为商店队列仅取决于当前时间和固定的外部到达时间。 由于考虑了每个可能的下一个商店，因此每个可能的完整订单都显示为 DP 转换序列。 因此，全掩模的最小值是最佳调度。 

## Python 解决方案```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    t = list(map(int, input().split()))

    arrivals = [[] for _ in range(n)]
    for _ in range(m):
        s, u = map(int, input().split())
        arrivals[s - 1].append(u)

    prefix = []
    for i in range(n):
        arrivals[i].sort()
        cur = 0
        pref = [0]
        for x in arrivals[i]:
            cur = max(cur, x) + t[i]
            pref.append(cur)
        prefix.append(pref)

    size = 1 << n
    inf = 10**30
    dp = [inf] * size
    dp[0] = 0

    for mask in range(size):
        cur = dp[mask]
        if cur == inf:
            continue

        for i in range(n):
            if (mask >> i) & 1:
                continue

            cnt = bisect_right(arrivals[i], cur)
            finish_queue = prefix[i][cnt]
            nxt_time = max(cur, finish_queue) + t[i]

            nxt = mask | (1 << i)
            if nxt_time < dp[nxt]:
                dp[nxt] = nxt_time

    print(dp[-1])

if __name__ == "__main__":
    solve()
```预处理部分将每个商店的外部队列转换为前缀完成时间。 索引处的值`k`意味着在服务第一个之后`k`顾客，届时商店免费。 

DP 部分遵循上述子集转换。 掩码存储为整数，这使状态表示保持紧凑。 由于只有`2^18`状态，迭代所有掩码是可行的。 

二分查找使用`bisect_right`而不是`bisect_left`因为恰好在奥金奈到达时间到达的顾客仍然先进入队列。 表达式`max(cur, finish_queue)`处理两种情况：要么队列已空，要么奥金奈必须等待。 

不需要溢出处理，因为 Python 整数会自动增长。 大的哨兵值仅用于表示不可达状态。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(2^n * n * log m)`| 每个子集都会尝试下一个商店，并且每个转换都会在商店的到达列表中执行一次二分搜索。 |
 | 空间|`O(2^n + m)`| DP数组存储所有子集状态，预处理存储所有客户到达。 |

 最大的状态数是`262144`，且转换次数只有几百万。 预处理一次性处理大量客户，因此该解决方案完全符合限制。

 ## 边缘情况

 对于第一个边缘情况，请考虑：```
1 1
5
1 0
```DP 从时间 0 开始。二分查找发现队列中已有一名客户，因为到达时间等于当前时间。 前缀队列完成时间为 5，因此 Auchenai 在时间 5 开始，在时间 10 结束。 

对于空队列：```
1 0
5
```二分搜索返回零个客户。 存储的队列完成为零，因此转换变为`max(0, 0) + 5`，给出正确答案5。 

对于已经离开的老顾客：```
1 1
3
1 0
```如果 Auchenai 可以在时间 10 到达商店，二分搜索将包括客户，但前缀完成将为 3。转换使用`max(10, 3) + 3`，给出 13。旧队列历史记录在清除后不会产生延迟。
