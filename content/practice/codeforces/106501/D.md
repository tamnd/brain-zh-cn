 ## 解决方案
 ## 问题理解

 我们有一行由整数数组表示的图块`b`。 我们添加相同的非负值`x`到每一块瓷砖。 在此操作之后，我们希望该行在两个图块之间的某个位置可拆分，以便左侧的总和等于右侧的总和。 任务是找到尽可能小的`x`，或报告没有值`x`可以使这样的分裂成为可能。 

假设我们在位置后分割`i`， 在哪里`1 <= i < n`。 设原始前缀和为`P`，并令总和为`S`。 添加后`x`对于每个元素，左侧都会获得`i*x`右侧收益`(n-i)*x`。 条件变为：`P + i*x = (S - P) + (n-i)*x`数组长度可以达到`2 * 10^5`所有测试用例的总计。 这排除了尝试许多可能的值`x`，因为答案可以大到`10^18`。 解决方案必须仅检查每个元素固定次数，给出预期目标`O(n)`per test case.

 主要的边缘情况来自分割位置和系数`x`。 

A split exactly in the middle has`2*i-n = 0`。 在这种情况下，改变`x`对双方的影响是平等的，因此无助于解决不平衡问题。 例如：```
Input:
1
2
1 2
```唯一的分割还剩总和`1+x`和正确的总和`2+x`。 它们的不同之处在于`1`永远，所以答案是`-1`。 粗心的实现除以`2*i-n`如果不处理零就会在这里失败。 

另一种边缘情况是数组已经可分离。 例如：```
Input:
1
3
1 2 3
```第二个元素之后的分割给出`1+2 = 3`， 所以`x = 0`已经有效。 即使其他正值也有效，最小答案必须保持为零。 

第三种情况是有效的分割需要进行较大的调整。 例如：```
Input:
1
5
1 2 3 4 5
```三个元素后的分割给出：`6 + 3x = 9 + 2x`所以`x = 3`。 仅检查较小的值`x`会错过这个答案。 

## 方法

 直接的暴力想法是尝试每一个可能的分割和每一个可能的值`x`直到找到解决方案。 分割部分很容易用前缀和来处理，但是`x`不受小数的限制。 在最坏的情况下，测试可能的值变得不可能，因为有效答案可能达到`10^18`。 

有用的观察来自于重新排列相等条件。 对于固定分割位置`i`：`P + i*x = S - P + (n-i)*x`移动所有项给出：`(2*i-n)*x = S - 2P`现在，每个分割位置都给出一个具有一个未知数的线性方程。 我们不需要寻找`x`; 我们可以计算该分割的唯一可能值。 

如果`2*i-n`为零，那么分割要么适用于每个`x`或者没有。 唯一有用的情况是当`S - 2P`也为零，给出`x = 0`。 

否则，候选值为：`x = (S - 2P) / (2*i-n)`仅当它是整数且非负时我们才接受它。 检查每个分割并保留最小的有效候选者给出了答案。 

暴力破解之所以有效，是因为分割条件很简单，但它会失败，因为可能的调整量并不小。 代数变换完全消除了搜索，并将问题转化为线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n * x 的范围) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算总和`S`原始数组的。 我们需要这个值，因为每个分割都会将前缀与剩余的后缀进行比较。 
2. 扫描可能的分割位置`1`到`n-1`同时保持当前的前缀和`P`。 每个位置代表最终数组可能被分隔的一个可能位置。 
3. 对于当前的分割，计算`left = 2*P - S`和`right = 2*i - n`。 这种分割的方程是`left + right*x = 0`，这给出了唯一可能的值`x`。 
4.如果`right`为零，单独处理。 当以下情况时，分割不会改变`x`变化，所以它仅在以下情况下有效`left`也为零。 在这种情况下，候选人的答案是零。 
5. 如果`right`不为零，检查是否`-left`可以整除`right`。 如果它不可整除，则此分割不能产生整数值`x`。 如果它是可整除的，则计算候选值并仅在其非负时保留它。 
6. 返回找到的最小候选者。 如果没有分割产生有效的候选者，则返回`-1`。 

为什么它有效：对于每个可能的分割，等式条件是一个线性方程`x`。 分割可以没有有效的整数解，也可以有一个有效值，或者当双方已经相等并且系数`x`为零。 该算法会检查每个可能的分割，并准确考虑可以满足其方程的值，因此不会错过任何有效答案，也不会接受无效答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    b = list(map(int, input().split()))

    total = sum(b)
    prefix = 0
    ans = None

    for i in range(1, n):
        prefix += b[i - 1]

        a = 2 * prefix - total
        c = 2 * i - n

        if c == 0:
            if a == 0:
                candidate = 0
            else:
                continue
        else:
            value = -a
            if value % c != 0:
                continue
            candidate = value // c

            if candidate < 0:
                continue

        if ans is None or candidate < ans:
            ans = candidate

    print(-1 if ans is None else ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```该解决方案首先存储总和，因为每次拆分都会将前缀与该前缀的补集进行比较。 在扫描过程中，`prefix`是当前分割之前的总和，因此表达式`2 * prefix - total`代表两侧之间的原始差异。 

变量`c`是系数`x`。 当它为零时，除法是不可能的，代码直接检查特殊情况。 这可以避免被零除错误并正确处理中间分割。 

对于非零`c`，代码在执行整数除法之前检查整除性。 这很重要，因为 Python 的整数除法会默默地截断非整数答案，这可能会产生无效结果。 最终比较保留最小的有效非负值。

 ## 边缘情况

 对于中间的分割情况：```
Input:
1
2
1 2
```算法检查`i = 1`。 系数`2*i-n`为零，而`2*prefix-total`是`-1`。 由于分割差不能通过向两侧添加相同的值来改变，因此算法拒绝它并返回`-1`。 

对于已经平衡的数组：```
Input:
1
3
1 2 3
```在`i = 2`，前缀和为`3`， 所以`2*prefix-total`变为零。 系数非零，生成的候选值为`0`。 该算法保留该值，因为它是最小的可能非负答案。 

对于需要调整的情况：```
Input:
1
5
1 2 3 4 5
```在第三个元素之后的分割处，前缀和为`6`。 等式变为：`(2*6-15) + (6-5)x = 0`简化为：`-3 + x = 0`所以`x = 3`。 扫描直接找到这个候选者，而不尝试值`x`。 

对于负数的情况：```
Input:
1
4
10 -10 10 -10
```总和为零。 第一次分割后，前缀和为`10`，给出一个候选者`20`，但后来的分裂产生`0`。 由于每个分割都会被检查，算法不会停在第一个可能的答案上，而是正确返回最小值。
