 ## 解决方案
 ## 问题理解

 我们被要求分析在一圈石堆上进行的两人游戏。 每堆都有一定数量的石头。 玩家轮流从当前堆中取出正数的石子。 回合按顺时针方向移动，因此当玩家从堆中取出石子后`i`，下一个玩家必须从堆中移走石子`i+1`，在最后一堆之后绕到第一堆。 轮到自己时遇到空堆的玩家就输了。 迈克总是先行。 

输入描述了多个测试用例，每个测试用例指定了桩的数量及其大小。 输出应该说明如果双方都发挥最佳，谁将获胜。 一个关键的观察结果是桩的数量相对较少（`n ≤ 50`）但石头的数量可能很大（`a_i ≤ 10^9`）。 这排除了任何按顺序模拟每个可能的移动的算法，因为这可能需要数十亿次操作。 

当所有桩具有相同大小时，会出现一个重要的边缘情况。 例如，如果`n = 2`两堆都有`100`石头，迈克从第一堆石头中取出一些石头。 然后乔可以在下一堆上匹配他的动作，并且由于游戏是对称的，迈克将被迫首先遇到空堆。 仅查看第一堆的幼稚解决方案可能会错误地宣布迈克为获胜者。 另一个边缘情况是单堆：迈克只需移走所有石子并立即获胜。 

## 方法

 暴力解决方案将尝试模拟所有可能的动作。 在每一回合中，我们可以尝试删除 1 最多`a_i`从当前堆中取出石头，递归计算获胜者。 这种方法是正确的，因为它直接遵循游戏规则，但其复杂性却令人望而却步：每堆最多可以有`10^9`石头，使得详尽的模拟不可行。 

关键的见解来自于观察每个玩家必须按顺时针顺序移动到下一堆。 第一个遇到一堆石头数量少于循环经过次数的玩家将会失败。 换句话说，在起始序列中严格小于所有先前堆的第一堆决定了获胜者，因为前一个玩家无法强迫对手在该点之后获胜。 对于这个问题，它简化为一个简单的检查：从头开始迭代一堆堆，并找到迈克无法匹配乔潜在镜像动作的第一堆。 如果迈克首先拥有严格较小的一堆，则乔获胜； 否则，迈克立即获胜。 

这一观察结果将潜在的指数问题转化为堆数量的线性问题。 我们可以在 O(n) 时间内解决每个测试用例，即使对于上限也很有效`t = 1000`测试用例。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(Σ a_i^n) | O(Σ a_i^n) | O(n) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 这使我们能够循环所有游戏场景。 
2. 对于每个测试用例，读取桩数`n`和桩尺寸的数组`a`。 
3. 初始化变量`winner`到`"Mike"`作为默认值。 
4. 从第一个堆开始迭代。 如果您遇到的堆严格小于之前的最小值，则意味着迈克无法安全地继续，而不冒乔的镜像策略的风险。 更新`winner`到`"Joe"`并打破循环。 在实践中，由于迈克移动的第一堆是决定性的堆，迭代只需要识别乔可以利用的最早的堆。 
5. 打印每个测试用例的获胜者。 

为什么有效：游戏是连续的，每一步都被迫进入下一堆。 首先到达一堆的棋子数量少于匹配对手优势所需的棋子的玩家就输了。 通过扫描一次牌堆，我们可以确定谁将首先达到这种失败条件。 这保证了正确性，因为一个玩家对最佳游戏的任何偏离只会让另一个玩家的获胜优势更加明显。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    winner = "Mike"
    for i in range(n):
        if a[i] < min(a[:i], default=a[i]):
            winner = "Joe"
            break
    print(winner)
```说明：我们有效地读取多个测试用例的输入。 这`min(a[:i], default=a[i])`安全地处理第一次迭代。 车
