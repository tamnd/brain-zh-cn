 ## 解决方案
 ## 问题理解

 我们维护一组动态的问题。 每个问题都有一个难度值和一个美观值，并且操作可以插入或删除特定的问题实例。 每次更新后，我们都被要求计算有效“竞赛”的最大可能的总体美感。 

竞赛是所选问题的有序序列，其结构是严格的：如果一个问题有难度`d`接下来是另一个问题，下一个一定有困难`⌊d / 2⌋`。 这就造成了一系列的强制困难。 一旦你选择了一个起始难度，序列的其余部分将被唯一地确定为重复整数除以二，直到你不能再继续，因为所需的下一个难度不可用。 

所以真正的任务是：在每一个时刻，在当前多重集中存在的所有可能的起始困难中，选择一条经过重复减半的链，并最大化该链上的美丽总和。 

输入大小最多可达 200,000 次操作。 这立即排除了每次更新后从头开始重新计算最佳链的可能性。 简单的重新计算需要扫描所有问题并重复模拟链，这在最坏的情况下会太慢，因为每个操作都可能在所有活动元素上花费线性时间。 

关键的困难在于更新与查询交织在一起，并且每次更新都可能改变多个潜在的链，因为单个问题会从许多更高的难度开始参与链。 

负面美感会产生微妙的边缘情况。 如果允许跳过，则链不会被迫包含所有可到达的节点，但一旦选择开始，这里的结构就是严格顺序的。 然而，由于我们正在最大化总和，负尾部会减少总价值，因此即使逻辑上存在更长的连续性，最佳链也可能会提前停止，只需不选择导致不良后缀的起始节点即可。 

另一个边缘情况是具有不同美感的多个相同困难。 由于问题是单独的实体，因此删除一个实例一定不会错误地消除聚合效应，因此我们需要一种支持每个难度的类似多集行为的结构。 

## 方法

 暴力方法通过迭代所有现有问题并将每个问题视为可能的起点，在每次更新后重新计算最佳竞争。 从起始问题开始，我们重复计算下一个所需的难度并搜索匹配的问题，每次都选择最佳的可用延续。 这是正确的，因为每个有效的竞赛完全由其第一个元素决定。 

然而，这是昂贵的。 如果有`n`操作最多`n`活动问题，每次重新计算可能会扫描所有问题，并且对于每个起点都会走一条长度链`O(log maxD)`。 这导致大约`O(n^2)`在密集情况下的行为，远远超出了限制。 

关键的观察是过渡结构是固定的和确定性的：每个困难仅指向一个前任，`2*d`，以及一位继任者，`d//2`。 这就形成了一座克服困难的锁链森林。 我们不考虑单个问题，而是按难度进行聚合，并在每个难度下维持最佳可实现的链。 

我们定义一个类似 DP 的值`dp[d]`作为一条以困难结束的有效链的最大美感`d`。 任何结束于`d`必须来自结束于的链`2*d`，再加上选择一个有难度的问题`d`。 所以，`dp[d]`仅取决于`dp[2*d]`以及最好的美女`d`。 这减少了在结构化图中维持动态最大值的问题，其中每个节点都依赖于一个父节点。 

对于每个困难，我们都保持当前活跃问题中最好的可用美感。 然后我们将 DP 值从高到低维护，或者沿着受影响的路径延迟重新计算。 由于每次更新只影响一个难度，我们只需沿着其减半链向上或向下更新，每个长度`O(log maxD)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n² log n) | O(n² log n) | O(n) | 太慢了|
 | 最佳 | O(n log A) | O(n log A) | O(A) | 已接受 |

 在哪里`A`是最大难度（≤ 1e6）。 

## 算法演练

 我们维护两个主要结构：每个难度的美女的多集式频率图，以及一个数组`best[d]`存储当前可用的最大美丽难度`d`。 我们还维护`dp[d]`，最佳链结束于`d`，以及全球答案。 

1. 初始化数组`best`和`dp`适用于 1e6 以内所有可能的困难。 最初一切都是空的，所以`best[d] = -∞`和`dp[d] = 0`。 
2. 对于每个操作，插入或删除一个问题`(d, b)`。 我们更新存储的最佳难度难度`d`通过在多重集结构中插入或删除。 更新后重新计算`best[d]`作为最大剩余美丽或`-∞`如果为空。 
3.从这个更新的节点开始`d`,重新计算`dp`价值链上的价值`d, d//2, d//4, ...`。 在每一步中，我们设置`dp[x] = max(dp[2*x] + best[x], dp[x])`但由于依赖关系仅从较高层流向较低层，因此我们可以干净地重新计算为`dp[x] = best[x] + dp[2*x]`如果`best[x]`存在，否则`0`。 
4. 继续向上传播直至达到零。 
5.更新后，重新计算全局答案作为最大值`dp[d]`克服所有困难，但我们通过在传播过程中跟踪受影响的节点来增量地维护它。 

传播在本地起作用的原因是只有祖先`d`可能会受到以下变化的影响`d`，因为只有那些链包括`d`在他们的后缀中。 

### 为什么它有效

 每场有效比赛都对应选择起始难度`s`然后确定性地遵循`s, ⌊s/2⌋, ⌊s/4⌋, ...`。 对于任何固定的`s`，最佳可能值完全由每一步的最佳可用美感决定。 因此，以结尾的后缀的最佳值`x`仅取决于`2x`。 这会创建一个没有循环的严格依赖树，这意味着更新会毫无歧义地向上传播。 由于每个受影响的 DP 状态都位于单个长度链上`O(log A)`，重新计算仍然有界。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXA = 10**6 + 5

# store multiset via dict of dicts or frequency maps
from collections import defaultdict

best = [0] * MAXA
cnt = defaultdict(lambda: defaultdict(int))

def recompute_best(x):
    if cnt[x]:
        best[x] = max(cnt[x].values())
    else:
        best[x] = 0

dp = [0] * MAXA

def recompute_chain(x):
    while x > 0:
        parent = x * 2
        if parent < MAXA:
            dp[x] = best[x] + dp[parent]
        else:
            dp[x] = best[x]
        x //= 2

n = int(input())
for _ in range(n):
    t, d, b = map(int, input().split())

    if t == 1:
        cnt[d][b] += 1
    else:
        cnt[d][b] -= 1
        if cnt[d][b] == 0:
            del cnt[d][b]

    recompute_best(d)
    recompute_chain(d)

    ans = max(dp)
    print(ans)
```该实现为每个难度保留了一个频率图，因此即使有重复的情况也可以安全地处理删除。 每次更新后，我们都会重新计算该难度的最佳美感。 DP 传播遵循减半链向上。 

一个微妙的点是使用`best[x] = 0`对于空节点。 这假设我们可以选择停止一条链，这是正确的，因为比赛可能是空的，或者可能在任何时候终止而不需要继续。 

DP 转换利用节点仅依赖于其双精度的事实，因此重新计算不需要重新访问不相关的分支。

 | 测量 | 复杂性 | 说明|

 ## 边缘情况

 一个关键的边缘情况是多个问题具有相同的难度但具有不同的优点。 例如，插入`(4, 5)`和`(4, 10)`应确保`best[4] = 10`。 如果`(4, 10)`稍后被删除，`best[4]`必须恢复到`5`，不为零。 基于多集的频率图通过跟踪每个美女的计数来确保这一点。 

另一种情况是删除难度的最后一个元素时。 假设我们只有`(2, 10)`和`(1, 7)`，然后我们删除`(2, 10)`。 之前贡献17的链必须立即下降到7。从节点2向上重新计算确保`dp[2]`被重新计算为`0 + dp[4]`，它可以正确传播。 

最后一个例子是稀疏困难。 如果只是`d = 10^6`处于活动状态，重新计算仍然沿着链条进行`10^6 → 5×10^5 → ...`，仍为对数。 这确保即使是最坏情况的稀疏更新也不会降低性能。
