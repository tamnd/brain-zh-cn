 ## 解决方案
 ## 问题理解

 我们给出了固定大小的嵌入空间$k$。 我们构建的每个句子都是一个单词序列，每个单词的作用就像这个嵌入向量上的一组确定性“写入操作”。 

我们从长度为零的向量开始$k$。 当我们在句子中放置一个单词时，它会覆盖某些坐标：每个单词都有几对$(p, v)$，这意味着当使用这个词时，坐标$p$被设置为值$v$，替换之前存在的任何内容。 单词严格从左到右处理，因此后面的单词可以覆盖前面的单词。 

任务是决定我们是否可以将一些给定的单词（每个单词最多使用一次）排列成一个序列，该序列的最终嵌入恰好成为目标向量$t$。 我们可以使用任何单词子集和任何顺序。 

关键的结构细节是操作不是相加的。 它们是作业。 这从根本上解决了为每个坐标选择最后一个写入器的问题。 

限制条件$k, w \le 100$表明任何涉及的方法$O(w^2)$或者$O(wk)$很容易就可以了，而所有排列的指数排序则不然。 尝试所有词序的天真的尝试需要$w!$，即使对于$w = 15$，更不用说100了。 

一个微妙的边缘情况来自于覆盖交互。 一个设定坐标的词$p$正确地稍后可能会被另一个也触及的词覆盖$p$。 相反，如果将一个在本地看来错误的单词放在冲突的分配之后，则可能会变得正确。 

另一个重要的边缘情况是同时覆盖多个坐标的单词。 单个单词可能会满足某些坐标，同时破坏其他坐标，这意味着我们必须进行全局推理，而不是贪婪地针对每个坐标进行推理。 

## 方法

 强力解释是尝试每个单词子集的每种顺序。 对于每个候选序列，我们模拟嵌入构造并检查它是否与目标匹配。 这是正确的，因为它直接遵循流程规则。 问题是规模：有$w!$所有单词的排列，甚至限制到子集仍然留下$2^w \cdot w!$，这远远超出了任何限制。 

结构性突破是不再将问题视为排序单词，而是将其视为为每个坐标分配责任。 由于每个位置的最终值$p$必须完全是$t_p$，最后一个词影响$p$必须正确设置。 这表明我们只关心哪个单词是每个坐标的最终作者。 

如果我们对每个坐标固定哪个单词负责其最终值，那么排序约束就变成局部的：如果单词$A$负责协调$p$，和词$B$负责协调$q$，一个字写入多个坐标时必须保证一致性。 这将问题转化为选择一组能够一致地“解释”所有坐标的单词。 

强制一致性的一种自然方法是将每个单词视为候选“配置文件”：它贡献部分任务，并且无论它被选择负责，其所有贡献都必须与目标相匹配。 那么问题就变成选择单词的子集，使得每个坐标都被至少一个正确书写的单词覆盖，并且不会出现矛盾。 

关键的观察是，由于每个单词都写入一组固定的坐标，因此如果曾经使用过某个单词，则它必须与其写入的所有坐标上的目标兼容。 否则，它永远不可能是这些坐标的最后一个写入者，并且只能充当非最终填充符，这是毫无意义的，因为覆盖总是可能且不必要的。 

因此，每个可用的单词都必须是“局部一致的”：对于每个$(p, v)$它定义了$v = t_p$，或者它不能用作该坐标的最终贡献者。 但即使它是局部一致的，我们仍然需要覆盖：每个坐标必须至少有一个单词可以正确书写它。 

这将问题简化为检查我们是否可以选择单词，使得对于每个坐标$p$, 至少存在一个字写$p$作为$t_p$。 如果存在这样的覆盖范围，我们可以通过以任何顺序放置所选单词来构建有效的排序，因为不会发生冲突：所有所选的分配都与目标一致。

 | --- | --- | --- | --- |
 | 暴力破解单词排列 |$O(w! \cdot k)$|$O(k)$| 太慢了|
 | 协调覆盖范围减少 |$O(wk)$|$O(wk)$| 已接受 |

 ## 算法演练

 我们在单词和坐标之间构建了二分式覆盖结构。 

1. 对于每个单词，我们扫描它的所有$(p, v)$对。 我们标记该单词是否与这些坐标的目标兼容。 一个字兼容坐标$p$如果它不写$p$，或者直接写成$t_p$。 

这确保了我们永远不会考虑一个会永久破坏它所接触的坐标的单词。 
2. 我们丢弃与任何书面坐标上的目标直接矛盾的任何单词。 

一旦一个单词被丢弃，它就不能出现在任何有效的结构中，因为它永远不可能是它修改的坐标的最后一个编写者。 
3.对于剩下的每个单词，我们记录它可以正确设置哪些坐标，意味着所有$p$使得它的值等于$t_p$。 
4. 现在我们检查每个坐标是否$p$至少有一个剩余单词可以正确设置它。 

这是核心可行性条件：由于最终值$p$必须来自某个词，我们至少需要一个候选来源。 
5. 如果任何坐标有零个候选项，我们立即得出不可能性的结论。 
6. 否则，我们通过选择所有剩余单词来构造输出。 他们的顺序无关紧要，因为他们执行的每项任务都与目标一致。 

构建步骤是安全的，因为所有选定的单词只写入正确的值，因此任何顺序都可以保持正确性。 

### 为什么它有效

 嵌入过程是一系列覆盖，但每个坐标的最终值仅取决于接触它的最后一个单词。 如果每个使用的单词仅分配与目标一致的值，则任何坐标都不会被迫偏离其目标值。 相反，如果某个坐标没有能够正确分配它的单词，则该坐标不可能有最后一个写入者，从而导致目标无法到达。 这创建了必要且充分的每坐标覆盖条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    k, w = map(int, input().split())
    t = list(map(int, input().split()))

    words = []
    valid = [True] * w

    for i in range(w):
        parts = input().split()
        name = parts[0]
        mi = int(parts[1])
        writes = []
        ok = True

        idx = 2
        for _ in range(mi):
            p = int(parts[idx]) - 1
            v = int(parts[idx + 1])
            idx += 2

            writes.append((p, v))
            if v != t[p]:
                ok = False

        valid[i] = ok
        words.append((name, writes))

    if not any(valid):
        print("IMPOSSIBLE")
        return

    covered = [False] * k

    for i in range(w):
        if not valid[i]:
            continue
        for p, v in words[i][1]:
            covered[p] = True

    for i in range(k):
        if not covered[i]:
            print("IMPOSSIBLE")
            return

    res = []
    for i in range(w):
        if valid[i]:
            res.append(words[i][0])

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```该实现首先过滤与目标明确写入的任何坐标立即相矛盾的单词。 这是我们需要在单词级别强制执行的唯一全局约束，因为任何矛盾都会使该单词不可能成为该坐标的最终编写者。 

过滤后，我们计算坐标的覆盖范围。 如果至少有一个幸存的字写入了正确的值，则认为可以实现坐标。 这确保了每个职位都有潜在的最终分配来源。 

最后，我们以任意顺序输出所有幸存的单词。 顺序并不重要，因为没有剩余的单词会引入冲突的分配。 

这里的一个常见错误是尝试重建实际的最小序列或执行贪婪放置。 这是不必要的，因为可行性仅取决于兼容编写器的存在，而不取决于它们之间的排序约束。 

## 工作示例

 ### 示例 1

 输入：```
3 3
1 2 1
a 1 1 1
b 1 2 1
c 1 3 1
```所有字都是单独兼容的，因为每个字只在适用的情况下写入正确的值。 

我们跟踪覆盖范围：

 | 词| 写 | 覆盖坐标|
 | --- | --- | --- |
 | 一个 | (1,1) | 1 |
 | 乙| (2,1) | 2 |
 | c | (3,1) | 3 |

 所有坐标都被覆盖，因此输出是所有单词的任意顺序，例如：```
a b c
```这表明一旦兼容性成立，排序就无关紧要了。 

### 示例 2

 输入：```
2 2
1 2
a 1 1 1
b 1 1 2
```字 a 对坐标 1 有效。字 b 无效，因为它将坐标 1 设置为 2，这与目标 1 相矛盾。 

覆盖范围检查：

 | 坐标| 被有效词语覆盖 |
 | --- | --- |
 | 1 | 一个 |
 | 2 | 无 |

 坐标 2 从来没有正确书写，所以答案是：```
IMPOSSIBLE
```这表明任何坐标缺少一个兼容编写器都会导致问题无法满足。

 ## 边缘情况

 当一个单词写入多个坐标时，会出现一种棘手的情况，其中一些与目标匹配，而另一些则不匹配。 例如，如果一个单词设置$p_1$正确但是$p_2$错误地，它根本不能使用，因为它会在$p_2$如果放在最后，它也会破坏中间状态。 

另一种边缘情况是坐标仅由在其他地方也发生冲突的单词书写。 即使每个坐标单独有一个候选词，如果所有候选词由于其他坐标而全局无效，则必须完全删除该单词。 过滤步骤通过基于任何不匹配而不是基于每个坐标的允许性拒绝单词来处理这个问题。 

最后，多个单词严重重叠的情况是安全的，因为我们从不依赖排序约束。 由于所有剩余的单词都与每个书面坐标上的目标一致，因此它们的相互作用在正确性方面是可交换的，尽管该过程通常在数学上不是可交换的。
