 ## 解决方案
 ## 问题理解

 我们给定一个大整数$p$。 每个测试用例都要求我们查看所有因式分解$p = a \cdot b$，其中两者$a$和$b$是正整数。 对于每个这样的对，都会构建一个特殊的序列$(a,b)$将两个数字移到一起：在步骤$n$，该值是一个类似分数的表达式$\frac{a+n}{b+n}$。 问题只关心这些值是否是整数。 

如果满足以下条件，则该序列中的术语被认为是“好”的：$(a+n)$可以整除$(b+n)$。 的“诚信”$(a,b)$是从开始的最大前缀长度$n=0$这样前缀中的每个项都是一个整数。 我们被要求计算有多少次因式分解$p = a \cdot b$产生至少 3 的完整性，并且对于这些分解输出相应的$b$按排序顺序排列的值。 

关键约束是$p \le 10^{18}$，因此枚举所有对$(a,b)$只能通过约除数枚举来实现$O(\sqrt{p})$每个测试用例。 自从$t \le 20$， 甚至$O(\sqrt{p})$是可以接受的，但是诸如检查所有对之类的事情$p$或者对每个除数进行深入模拟序列都会失败。 

一个微妙的点是，该条件涉及连续三个轮班$n=0,1,2$。 一个天真的错误是假设只进行检查$n=0$或仅$n=0,1$就足够了。 事实并非如此，因为可分性约束以非平凡的方式通过移位对传播。 

打破粗心推理的边缘情况：

 如果$p=16$， 考虑$(a,b)=(8,2)$。 然后$n=0$:$8/2=4$，整数。$n=1$:$9/3=3$，整数。$n=2$:$10/4=2.5$，不是整数，因此完整性恰好是 2，而不是 3。仅检查前两个步骤的解决方案会错误地计算这一对。 

如果$p$是素数，唯一的因子对是$(p,1)$和$(1,p)$，并且通常即使在第二个条件下也无法幸存，因此输出必须为零。 缺少这一点会导致对无效候选者进行不必要的计算。 

## 方法

 蛮力方法将迭代所有对$(a,b)$这样$ab=p$。 对于每一对，我们逐步模拟序列：检查是否$(a+n)\bmod(b+n)=0$为了$n=0,1,2$。 每次检查的时间都是恒定的，因此每对成本是恒定的。 

问题是因子对的数量。 在最坏的情况下，像这样的高度复合数$10^{18}$可以有以下顺序$10^5$除数，意思是$10^5$对。 这是边界，但仍然很好。 然而，通过嵌套循环生成所有对是不可能的； 我们必须枚举除数$O(\sqrt{p})$。 

关键的观察是一旦我们修复$b$，值$a$被确定为$a = p/b$。 所以整个问题简化为迭代除数$b$的$p$，并检查恒定数量的算术条件。 

对于每个除数$b$，我们测试：$$\frac{p/b + n}{b+n} \in \mathbb{Z} \quad \text{for } n=0,1,2$$这只是模块化算术检查，不需要模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解所有对 |$O(d(p))$昂贵的支票|$O(1)$| 构建对太慢 |
 | 除数枚举+常量检查|$O(\sqrt{p})$每个测试用例|$O(1)$| 已接受 |

 ## 算法演练

 ### 1. 枚举所有除数$b$的$p$我们迭代$i$从 1 到$\sqrt{p}$。 如果$i$划分$p$，然后我们得到两个候选人$b=i$和$b=p/i$。 此步骤确保我们只考虑每个有效因子对一次。 

### 2. 对于每个除数$b$, 计算$a = p / b$自从$ab=p$，这唯一地修复了该对。 没有自由了，所以一切条件仅取决于此$b$。 

### 3. 检查第一个条件$n=0$我们要求：$$\frac{a}{b} \in \mathbb{Z} \quad \Leftrightarrow \quad a \bmod b = 0$$这相当于$b^2 \mid p$。 如果失败，我们立即丢弃该对，因为完整性已经为零。 

### 4. 检查第二个条件$n=1$我们要求：$$(a+1) \bmod (b+1) = 0$$这是使用先前计算的直接算术检查$a$。 

### 5.检查第三个条件$n=2$我们要求：$$(a+2) \bmod (b+2) = 0$$如果所有三个条件都成立，我们存储$b$作为有效答案。 

### 6.排序并输出所有有效的$b$由于除数是成对生成的，没有保证顺序，因此我们在打印之前对最终列表进行排序。 

### 为什么它有效

 完整性条件仅取决于长度为 3 的固定有限前缀。每个条件都是一个独立的可分性约束，仅涉及$a$和$b$。 一次$a$由因式分解固定$p=b\cdot a$，不同除数之间不存在隐藏的依赖关系。 因此，独立检查每个候选就足够了，枚举所有除数可以保证完整性而不会重复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def valid(a, b):
    # check n = 0
    if a % b != 0:
        return False
    # n = 1
    if (a + 1) % (b + 1) != 0:
        return False
    # n = 2
    if (a + 2) % (b + 2) != 0:
        return False
    return True

def solve():
    t = int(input())
    for _ in range(t):
        p = int(input())
        res = []
        
        i = 1
        while i * i <= p:
            if p % i == 0:
                b1 = i
                a1 = p // i
                if valid(a1, b1):
                    res.append(b1)

                if i != p // i:
                    b2 = p // i
                    a2 = i
                    if valid(a2, b2):
                        res.append(b2)
            i += 1
        
        res.sort()
        print(len(res))
        if res:
            print(*res)

if __name__ == "__main__":
    solve()
```代码直接遵循算法结构。 辅助函数隔离了完整性检查，以便以干净且恒定时间的方式评估每个除数候选者。 除数循环小心地避免重复计算$i = p/i$，这发生在$p$是一个完美的正方形。 

一个常见的实现陷阱是忘记除数对的两个方向都必须被视为$(a,b)$，不仅仅是$(b,a)$。 另一种错误地假设只有$b$需要是一个除数$a$; 正确的条件严格基于移位的可分性检查。

 ## 边缘情况

 对于素数$p$，除数集非常小。 例如$p=13$只生产$(1,13)$和$(13,1)$。 两者均未通过$n=1$立即检查，因为$(a+1)$无法与$(b+1)$在这样的不对称对中。 

对于完美平方，除数对可以折叠成单个候选，并且如果相等的情况很容易重复计算$i = p/i$处理不仔细。 为了$p=36$, 除数$6$只出现一次，重复它会超出结果。 

对于非常大的$p$附近$10^{18}$，算术安全问题。 所有操作都必须保持在 64 位整数范围内，但 Python 可以自然地处理这个问题。 在具有固定宽度整数的语言中，在$a+2$或者$b+2$是一个微妙的错误源。
