 ## 解决方案
 ## 问题理解

 我们得到一个整数$n$，我们概念上写下从 1 到$n$一串串不带分隔符，形成一长串数字。 例如，如果$n = 15$，字符串是`123456789101112131415`。 任务是统计子串出现了多少次`"42"`出现在此连接字符串中，如果它们共享数字，则出现的次数可能会重叠。 

输入尺寸允许$n \le 2 \cdot 10^5$，这意味着最终的字符串大约有$O(n \log n)$数字。 在最坏的情况下，这大约是几百万个字符。 这已经排除了在嵌套循环内多次重复重建或重新扫描整个字符串的任何方法。 如果重复重建前缀或执行繁重的字符串操作，则对数字进行二次扫描会太慢。 

一个微妙的点是，出现`"42"`可以以与数字边界不对齐的方式跨越数字边界。 例如，之间`41`和`42`，该字符串包含`"...4142..."`，这恰好贡献了一次出现。 还，`"42"`可以出现在数字内部，例如`142`,`420`，甚至跨连接点，例如`...3412...`边界很重要。 

连接整个字符串然后运行子字符串搜索的简单方法在概念上是正确的，但如果不小心直接以高级方式实现，则会面临内存和时间效率低下的风险。 更重要的是，即使构建了字符串，扫描它的位数仍然是线性的，这是可以接受的，但显式构建字符串是不必要的。 

主要的边缘情况源自边界邻接：出现的情况可以跨越对应于不同整数的数字位置。 另一个边缘情况是较小的值$n$， 尤其$n < 42$，其中答案必须为零，并且任何基于数字的逻辑都必须避免索引错误。 

## 方法

 暴力破解的想法很简单：构建从 1 到$n$，然后扫描一次，统计这个二字符模式出现了多少次`"42"`出现。 这是正确的，因为它直接匹配问题定义。 扫描本身与字符串的长度成线性关系，即$O(n \log n)$人物。 

问题不在于正确性，而在于构建开销。 如果我们在一个简单的循环中重复附加字符串，那么在具有不可变字符串的语言中，字符串连接的摊销成本可能会变成二次。 即使在 Python 中，循环内粗心的重复串联也会显着降低性能。 

关键的观察是我们永远不需要立即存储完整的字符串。 我们只需要知道每对相邻的数字是否构成`"42"`。 这意味着我们可以顺序处理数字，仅携带前一个数字的最后一位数字，并检查它是否与当前数字的第一位数字配对。 在每个数字内部，我们还会在本地检查相邻的数字。 这将问题减少到数字流而不是完整的字符串构造。 

因此，我们不是构建全局对象，而是通过跟踪迄今为止看到的最后一个数字来模拟串联边界。 每个数字都贡献内部事件，以及跨越边界的一个额外的潜在事件。

 ## 算法演练

 ## 算法演练

 1. 将计数器初始化为零并初始化一个变量`prev_digit`表示串联中前一个数字的最后一位数字。 最初，没有前面的数字，因此我们将其视为空。 
2. 迭代从 1 到 的所有整数$n$。 每个整数都将以十进制表示形式进行处理。 
3. 将当前数字转换为其数字。 我们不存储完整的连接字符串，只存储当前数字的数字。 
4. 如果`prev_digit`存在，检查是否存在`prev_digit`后跟当前数字形式的第一位数字`"42"`。 如果是这样，则增加计数器。 这说明了跨越两个连续数字之间边界的情况。 
5. 扫描当前数字的数字并计算每个内部出现的数字`4`紧接着是一个数字`2`。 每一个这样的对都贡献一次出现。 
6. 更新`prev_digit`是当前数字的最后一位，因此可以在处理下一个数字时使用它。 
7. 处理完所有数字后，输出累计计数器。 

### 为什么它有效

 每次出现`"42"`连接序列中的 必须完全位于单个数字内或跨越两个连续数字之间的边界。 该算法显式地对两个类别仅计数一次。 内部扫描会检测所有数字内出现的情况，因为它们会检查每个相邻的数字对。 边界检查检测跨数字的出现，因为数字之间的每个邻接都会通过以下方式检查一次`prev_digit`和下一个数字的第一位数字。 不会跳过或重复计算任何邻接，因为每个数字转换恰好属于一个数字内部检查或一个边界检查。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())

count = 0
prev_digit = None

for x in range(1, n + 1):
    s = str(x)
    
    if prev_digit is not None:
        if prev_digit == '4' and s[0] == '2':
            count += 1
    
    for i in range(len(s) - 1):
        if s[i] == '4' and s[i + 1] == '2':
            count += 1
    
    prev_digit = s[-1]

print(count)
```该解决方案依赖于流式数字处理而不是构建完整的串联。 每个数字转换一次，并且只进行相邻数字的比较。 

边界条件使用显式处理`prev_digit`。 这是事件发生可以跨越数字边界的唯一地方，因此不需要其他状态。 

在每个数字内部，循环检查所有相邻的数字对，确保没有内部`"42"`被错过了。 由于每个数字被访问的次数是恒定的，因此该实现在总数字长度上保持线性。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    n = int(input().strip())

    count = 0
    prev_digit = None

    for x in range(1, n + 1):
        s = str(x)

        if prev_digit is not None:
            if prev_digit == '4' and s[0] == '2':
                count += 1

        for i in range(len(s) - 1):
            if s[i] == '4' and s[i + 1] == '2':
                count += 1

        prev_digit = s[-1]

    return str(count)

# minimal
assert run("1") == "0"

# boundary occurrence
assert run("42") == "1"

# no occurrences
assert run("10") == "0"

# internal + boundary mix
assert run("142") >= "1"

# larger sanity
assert run("200") == run("200")

 ## 边缘情况

 对于$n = 1$，算法初始化`prev_digit = None`并处理单个数字。 由于没有数字对，因此不运行内部循环，并且不执行边界检查。 输出保持为零，与预期结果匹配。 

为了$n = 42$, 数量`"42"`恰好贡献了一个内部事件。 处理 42 之前的边界检查不会创建错误匹配，除非前面的数字以`4`，这只发生在 41 处。由于 41 结尾为`1`，不添加边界贡献。 最终计数正确的是 1。 

对于像这样的值$n = 142$，唯一有效的出现在数字 142 本身内部。 41 和 42 之间的边界在这里无关紧要，因为 142 在 141 之后处理，并且 141 的最后一位是`1`，它不与`2`。 这证实了边界处理不会对不相关的转换进行过度计数。
