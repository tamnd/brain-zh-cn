 ## 解决方案
 ## 问题理解

 我们得到一个由三个可能的字符组成的字符串：左括号、右括号和通配符。 每个通配符稍后都可以单独替换为左括号或右括号。 在所有替换之后，生成的字符串定义了一组有效的括号子序列，我们关心一个称为“美丽”的量。 

美感被定义为形成正确括号序列的子序列的最大可能长度。 正确的顺序是括号平衡，并且没有任何前缀的右括号多于左括号。 重要的是，我们获取的不是子字符串，而是子序列，因此在形成最佳有效结构时，我们可以任意删除中间的字符。 

任务是将每个通配符分配给括号类型，以使最佳可实现的平衡子序列变得尽可能小。 

约束 n 高达 4 · 10^6 迫使我们进入线性或近线性时间。 任何二次方，甚至是具有较大常数的 n log n，都有由于原始输入大小而导致超时的风险。 该结构还表明我们应该避免任何重复模拟许多分配的子序列匹配的方法。 

一个微妙的点是，子序列最优性忽略了相对位置之外的顺序限制。 即使字符串在本地高度不平衡，我们仍然可以通过跳过字符来提取平衡的子序列。 这意味着对最终字符串的天真贪婪模拟是不够的，除非我们仔细推理有多少个括号可以配对。 

当通配符集中在末尾或字符串已经严重不平衡时，就会出现边缘情况。 例如，如果字符串已经是除通配符之外的所有左括号，则最佳分配可能会故意减少可用的对。 修复角色后“始终尽可能平衡”之类的天真的想法失败了，因为我们正在对抗性地选择分配以最小化最终可实现的匹配。 

## 方法

 直接的强力策略是独立处理每个通配符，尝试两种选择，并计算所得完全固定字符串的美观度。 对于每个完整的字符串，我们计算最长的正确括号子序列，这相当于使用堆栈或平衡计数器贪婪地匹配括号。 使用 k 个通配符，这给出了 2^k 种可能性，并且每次评估成本为 O(n)，因此最坏的情况变为 O(n 2^n)，这在给定规模下是完全不可行的。 

关键的观察是我们实际上不需要知道分配后的精确匹配子序列结构。 固定字符串的美妙之处仅取决于有多少个左括号和右括号可以在非负前缀意义上配对，这是由前缀不平衡行为控制的。 通配符决策仅影响我们可以跨前缀分配的打开和关闭数量。 

我们可以不模拟匹配，而是将问题重新解释为控制打开和关闭的最终计数，同时尊重最佳子序列将从左到右贪婪地获取尽可能多的有效对。 这将问题从组合分配转移到平衡前缀容量：我们有效地决定早期可用的“开放供应”量与稍后出现的“关闭需求”量。 

一旦重新构建，该结构就变成了一个经典的前缀可行性最小化问题：我们希望强制尽可能多的不匹配的关闭，以便最大可堆叠对最小化。 这导致了一个贪婪的构造，我们决定每个通配符的最终括号类型，同时跟踪我们仍然必须放置多少个开放以防止早期过度关闭以及还有多少强制约束。

最佳解决方案减少为扫描一次字符串，并维护固定字符和未确定的通配符仍然“可用”的打开和关闭数量，然后以总是尽可能损害未来匹配的方式分配通配符。

 | 蛮力 | O(n·2^k) | O(n·2^k) | O(n) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们处理字符串，同时维护仍然可以从固定字符和剩余通配符中放置多少个开头和结尾。 关键思想是，每次遇到通配符时，我们都会根据是否要降低未来形成有效对的能力来选择其类型。 

我们维持两个柜台：我们仍然有能力放置的剩余开仓，以及剩余的平仓。 这些来自全局总计：每个“(”增加打开，每个“)”增加关闭，每个“？” 贡献一个灵活的单位。 

我们还保持运行平衡约束：由于任何有效的子序列都必须尊重前缀可行性，因此，如果我们尝试将字符解释为对堆栈有贡献，则最佳可能的匹配受到我们可以阻止前缀变为负数的次数的限制。 

贪心策略是分配通配符如下：

 1. 计算固定“(”和“)”的总数以及“?”的总数。 
2. 决定将通配符分为开号和闭号，这将最大限度地减少最终匹配对的数量。 由于匹配对需要一个开盘和一个闭盘，因此对手希望使限制边尽可能小。 
3. 从左到右处理字符串，分配每个“？” 在跟踪打开数量时，我们仍然必须分配“(”或“)”，以避免使前缀无法解释为有效的子序列结构。 
4. 每当分配时，一旦我们可以负担得起，就优先考虑尽早放置')'，因为过早的结束符号会降低以后形成长有效子序列的能力。 
5. 通过跟踪在给定构造的不平衡的情况下仍然可能存在多少强制匹配，隐式模拟最佳可能的子序列长度。 

该实现有效地减少了计算在对抗性分配下可以配对多少个括号，这变成了计算在前缀可行性约束下可实现的 min(opens, closes) 的约束最小值。 

### 为什么它有效

 任何正确的括号子序列都对应于将一个开头与稍后的结尾配对，以便前缀约束成立。 这意味着最终的答案从根本上取决于在累积太多关闭之前可以保持“可用”的打开数量。 对手的作用就是尽早破坏这种平衡。 

通过在从左到右扫描时始终根据打开和关闭的可用预算进行推理，我们保持不变，即剩余的不匹配潜力反映了未来可能的最佳配对。 与贪婪选择不同的通配符的任何替代分配要么延迟关闭，要么提前消耗打开，这两者都只能增加可匹配对的最终数量。 这表明贪婪分配对于最小化可实现的子序列长度而言是极值的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    fixed_open = s.count('(')
    fixed_close = s.count(')')
    q = s.count('?')

    # We want to minimize the maximum number of matched pairs.
    # Each pair consumes one '(' and one ')'.
    # So we reason in terms of how many effective opens/closes we can force.

    # Let total opens we will end up with:
    # fixed_open + x
    # closes: fixed_close + (q - x)

    # matched pairs is limited by min(opens, closes).
    # So we want to choose x to minimize min(fixed_open + x, fixed_close + q - x).

    # This is a classic V-shape minimum; optimal occurs when we push imbalance.

    # We try both extreme allocations and pick worst (since we are minimizing match capacity).
    # But adversary chooses x implicitly; we compute best achievable minimum.

    # The function is concave in x for min, so optimal at boundary:
    # x = 0 or x = q

    option1 = min(fixed_open, fixed_close + q)
    option2 = min(fixed_open + q, fixed_close)

    print(max(option1, option2))

if __name__ == "__main__":
    solve()
```该代码将整个问题压缩为计算固定括号和通配符，然后将所有通配符的两个极端分配评估为开或闭。 只有极端才重要的原因是 x 中两个线性函数的最小值在端点处最大化，因此当目标是最小化可实现的最佳配对时，任何混合分配都无法击败完全倾斜的分配。 

最终答案是两个最坏情况匹配能力中的最大值，对应于将所有灵活性推向一个方向或另一个方向。 

一个常见的陷阱是尝试直接模拟子序列。 这会超出无关紧要的结构，因为在对抗性构造下，后续最优性会崩溃为全局计数。 

## 工作示例

 考虑输入`((??)))))`。 我们将固定开盘次数计为 2 次，固定收盘次数计为 5 次，并有 2 个通配符。 

| x（通配符为 '(') | opens | closes | min(opens, closes) |
 | --- | --- | --- | --- |
 | 0 | 2 | 7 | 2 |
 | 2 | 4 | 5 | 4 |

 最佳的对抗选择是向更大的最小值保持平衡，给出 4。这对应于最大化尽管不平衡仍然可以形成多少对。 

现在考虑`()??)((?)?)()()?)??)?`在简化的推理视图中。 该字符串在本地已经相当平衡，但通配符允许移动不平衡。 如果我们将所有通配符放入一种括号类型中，那么我们要么使开口或闭合饱和，并且匹配瓶颈变得单向。 该公式评估两个极端情况并选择更强的极限情况，反映最佳分配后可实现的最差配对。 

这些示例表明，字符串的内部结构并不重要，因为子序列的灵活性吸收了排序约束。

 ## 边缘情况

 一种边缘情况是字符串没有通配符。 对于像这样的输入`((()))`，算法立即减少到固定计数，并且两个极端分配一致。 计算出的最小值保持不变，因为不存在恶化或改善平衡的灵活性。 

另一个边缘情况是所有字符都是通配符。 为了`??????`，两个极端的作业会崩溃为全部打开或全部关闭。 当进行对抗性解释时，两者在最坏的子序列意义上产生零可用配对，并且该公式正确地捕获了对称限制。 

第三种情况是严重倾斜的前缀，例如`((((((????`。 在这里，将所有通配符指定为 ')' 可以部分修复平衡，但将它们指定为 '(' 会使平衡变得更糟。该算法测试了两个极端，并正确识别出我们所能强制的最好结果完全由较强的一侧不平衡控制，而不需要任何前缀模拟。
