 ## 解决方案
 ## 问题理解

 我们有一个无向图，其中每个顶点都以偶数个关联边开始。 我们可以一条一条地删除边，但是只有当一条边的两个端点中至少有一个当前具有偶数度数时，才可以删除一条边。 任务是找到最大可能的移除数量并以有效的顺序输出边缘索引。 

输入描述了顶点和原始边。 输出是一系列边 ID，完全按照应删除这些边的顺序排列。 所有删除后的图不需要为空，因为某些边可能无法删除。 

限制很大：顶点和边的数量都可以达到 500000。这立即排除了重复搜索所有边或尝试不同删除选择的模拟。 需要围绕线性时间的算法，因为即使是 (O(m \log m)) 解决方案也需要仔细实现，而任何涉及多次遍历图的情况都会超出限制。 

关键的边缘情况来自每次删除后度数奇偶性的变化。 以偶数度开始的顶点在删除一条关联边后可能会变成奇数，因此仅检查初始图是不正确的。 

例如：```
3 3
1 2
2 3
1 3
```一个有效的最佳答案是：```
2
1 2
```删除边 1 后，剩余的度数为 1、1、2。边 2 仍然可以删除，因为顶点 3 的度数为偶数。 假设第一次删除使所有未来选择都不可能的解决方案将错过有效的删除。 

另一个重要的情况是断开连接的图：```
6 2
1 2
3 4
```该图不满足原始偶数条件，因此它不能出现在输入中。 实际的边缘情况是由几个偶数分量组成的断开图，例如：```
6 4
1 2
2 3
3 4
4 1
```只有一个组件有边缘，可以删除三个边缘。 该组件中的最后一条边无法删除，因为它的两个端点的度数均为 1。 

## 方法

 直接方法将重复扫描所有剩余边缘。 每当一条边至少有一个度数为偶数的端点时，我们将其删除并更新两个度数。 这是正确的，因为每个选择的删除都遵循规则。 然而，在最坏的情况下，我们可能会在每次删除后扫描所有 (m) 条边，从而导致 (O(m^2)) 次操作。 对于 (m=500000)，这远远超出了可能的范围。 

有用的观察来自于每个顶点最初都有偶数度这一事实。 该图的每个连接组件都有一个欧拉电路。 考虑沿欧拉电路的边的顺序。 如果我们将除了电路的最后一条边之外的那些边一一删除，则每次删除都是合法的。 

为什么会出现这种情况？ 在欧拉遍历中删除边之前，当前顶点仍然有偶数个未使用的关联边。 遍历成对地进入和离开顶点，因此被移除的边总是接触到剩余度数为偶数的顶点。 从组件中删除除一条边以外的所有边后，最后剩余的边的两个端点均为奇数，因此无法删除。 

这也证明了最大值。 包含至少一条边的连通分量不能丢失其最后一条边，因为最后一条边将留下两个 1 度的顶点。 由于每个非空组件必须保留至少一个边缘，因此每个组件只保留一个边缘是最佳的。 

问题被简化为找到所有组件的欧拉电路并输出每个电路中除该组件的最终边缘之外的每个边缘。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(平方米) | O(n + m) | 太慢了|
 | 最佳| O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 构建包含每个边 ID 的邻接表。 由于该图是无向的，因此每条边在邻接结构中出现两次。 
2. 对于每个尚未处理且至少有一个入射边的顶点，运行迭代 Hierholzer 遍历以构造其连通分量的欧拉回路。 
3. 存储欧拉遍历产生的边ID。 遍历只包含该组件的每个边一次。
 4. 将除欧拉序中最后一条边之外的该分量的所有边添加到答案中。 有意保留最后一个边缘，因为它是组件不可避免的剩余边缘。 
5. 继续，直到每个包含边缘的组件都已处理完毕。 输出收集到的删除序列。 

工作原理：不变的是每个组件都通过欧拉电路独立处理，并且该组件内部的删除顺序遵循有效的循环边顺序。 在具有 (s) 条边的分量的前 (s-1) 次删除期间，下一条欧拉边始终具有剩余度数为偶数的端点。 由于没有任何组件可以完全擦除，因此为每个组件保留一个边缘也是最好的结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    adj = [[] for _ in range(n)]
    for i in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append((v, i))
        adj[v].append((u, i))

    used = [False] * m
    ans = []

    for start in range(n):
        if not adj[start]:
            continue

        if all(used[e] for _, e in adj[start]):
            continue

        stack = [(start, -1)]
        circuit = []

        while stack:
            u, in_edge = stack[-1]

            while adj[u] and used[adj[u][-1][1]]:
                adj[u].pop()

            if adj[u]:
                v, eid = adj[u].pop()
                if used[eid]:
                    continue
                used[eid] = True
                stack.append((v, eid))
            else:
                stack.pop()
                if in_edge != -1:
                    circuit.append(in_edge)

        if circuit:
            ans.extend(circuit[:-1])

    print(len(ans))
    if ans:
        print(*[x + 1 for x in ans])

if __name__ == "__main__":
    solve()
```邻接列表存储边 ID 而不是仅存储相邻顶点，因为输出需要原始边编号。 这`used`数组可防止在 Hierholzer 算法期间无向边被取两次。 

使用 Hierholzer 的堆栈版本是因为递归 DFS 可以超出 Python 对具有数十万个顶点的图的递归限制。 当顶点没有剩余未使用的入射边时，算法会添加用于将该顶点输入电路的边。 这会产生相反的欧拉顺序，这仍然是有效的欧拉遍历，因为反转循环保留了其有效性。 

每个电路的最后一个边沿都会被跳过。 索引转换仅在打印时发生，因为输入和内部表示使用从零开始的边缘 ID。 

## 工作示例

 对于样本：```
3 3
1 2
1 3
2 3
```一种可能的欧拉阶是包含所有三个边的环。 

| 步骤| 欧拉边已移除 | 组件中的剩余边缘 |
 | --- | --- | --- |
 | 1 | 1 | 2 |
 | 2 | 2 | 1 |

 该算法输出两个删除并留下最后一条边。 剩余的边无法删除，因为它的两个端点的度数均为 1。 

方形循环：```
4 4
1 2
2 3
3 4
4 1
```可以按如下方式处理。 

| 步骤| 欧拉边已移除 | 剩余边缘 |
 | --- | --- | --- |
 | 1 | 1 | 3 |
 | 2 | 2 | 2 |
 | 3 | 3 | 1 |

 第四条边保留。 这证明了具有边缘的组件总是恰好贡献一个不可避免的边缘的规则。

 ## 边缘情况

 以三角形为例：```
3 3
1 2
1 3
2 3
```Hierholzer 创建了一个长度为 3 的欧拉回路。 该算法删除前两个电路边缘并保留第三个。 该不变量成立，因为每个移除的边都出现在循环的最后一个边之前。 

对于具有孤立顶点的图，例如：```
5 4
1 2
2 3
3 4
4 1
```仅处理前四个顶点。 顶点 5 没有边并且没有任何贡献。 答案是删除四个循环边中的三个。 

对于多个连接的组件：```
8 8
1 2
2 3
3 4
4 1
5 6
6 7
7 8
8 5
```每个周期都是单独处理的。 该算法在第一个分量中留下一条边，在第二个分量中留下一条边，同时删除其他六个边。 这与每个非空组件必须保留一个边缘的下限相匹配。
