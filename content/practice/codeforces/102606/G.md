 ## 解决方案
 ## 问题理解

 杰洛特与怪物战斗，怪物总是先被击中。 杰洛特可以在战斗前提高两项统计数据：攻击和防御。 增加一点攻击成本`a`皇冠，同时增加一点防御成本`b`皇冠。 升级可以是小数，因此最终的攻击和防御值不必是整数。 

升级后，杰洛特交易`max(0, attack - monster_defense)`每回合造成伤害。 杰洛特每次攻击后怪物都会失去生命值，只有在存活下来的情况下才会进行反击。 怪物交易`max(0, monster_attack - Geralt_defense)`损害。 由于杰洛特拥有无限生命值，因此唯一需要最小化的数量是怪物死亡之前受到的总伤害。 

对于每个测试用例，输入给出了两名战士的初始攻击和防御、怪物生命值、可用皇冠以及两次升级价格。 输出是杰洛特受到的最小可能伤害，写为约简分数，或者`-1`如果没有升级计划可以让他获胜。 

对于单个值的约束很小`n`，但最多可以有`10^4`测试用例。 花费的算法`O(n)`每个案例的时间可以达到大约`10^8`操作，并且在这样的循环中使用昂贵的分数算术在 Python 中会太慢。 该解决方案需要利用优化的数学形状，而不是模拟可能的升级。 

危险的情况是持续升级与离散数量的攻击相互作用的情况。 

如果杰洛特开始时没有有效的攻击，那么假设有固定的最大回合数是错误的。 例如：```
1
1 10 100 1
10 5 1 100
```杰洛特没有初始伤害，因为他的攻击力低于怪物的防御力。 他可以购买任意小的攻击增加，因此攻击次数不受原始攻击值的限制。 

另一个常见的错误是计算怪物的最终攻击次数。 如果怪物死于杰洛特的攻击，它不会反击。 例如：```
1
5 1 1 1
1 1 1 1
```杰洛特已经成交`4`造成伤害并立即杀死怪物。 答案是：```
0/1
```在每次杰洛特回合后增加怪物伤害的模拟会错误地输出正值。 

分数处理也很重要。 计划可能需要分数攻击增加，并且最终答案可能不是整数。 例如，最佳防御降低可以留下合理的每次攻击伤害量，因此浮点运算可能会失去精度。 

## 方法

 直接的方法是尝试每种可能的攻击升级量，计算用于防御的剩余资金，模拟需要多少次攻击，并保持最佳结果。 这是正确的，因为每个合法的升级选择都会被检查。 然而，升级值是连续的，因此有无限多种可能的选择。 即使我们只考虑所需的攻击次数，也可能有多达`n`每个测试用例的可能性。 穿过`10^4`情况下，这太慢了。 

有用的观察是，攻击升级仅与杀死怪物所需的回合数有关。 假设杰洛特正好需要`k`攻击。 实现这一目标的最便宜的方法是使他的伤害恰好足以满足：```
k * damage >= n
```任何额外的攻击伤害都不会减少怪物的攻击数量，因此只会浪费本可以用于防御的王冠。 

对于固定的`k`，我们可以计算出最小的攻击投入，然后将剩余的所有皇冠投入防御。 问题变成了寻找最好的可能`k`。 

当杰洛特已经拥有正伤害时，可能的攻击次数是有限的。 没有攻击升级他最多需要`ceil(n / base_damage)`攻击，更多的攻击升级只能减少这个数字。 我们可以最小化这个范围，但我们是用数学方法来实现的，而不是检查每个值。 

对于候选攻击次数`k`，受到的伤害是一个函数，其形式为：```
(k - 1) * max(0, C - T/k)
```对于常数`C`和`T`。 删除最大值运算后，这是整数上的凸函数或单调函数。 这意味着最小值只能出现在边界附近或导数为零的点附近。 检查几个相邻的整数值就足够了。 

当杰洛特以零伤害开始时，有两种特殊情况。 如果防御可以完全无效，而只留下少量资金用于攻击，那么答案立即为零。 否则，最佳攻击次数是最小的可行攻击次数，因为函数是递增的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个测试用例 O(n) | O(1) | O(1) | 很多情况下速度太慢 |
 | 最佳| 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.计算杰洛特当前的有效攻击力以及怪物当前对杰洛特的有效伤害。 如果杰洛特的攻击力已经足够，后面的公式就以此值作为起点。 
2.处理杰洛特攻击力为零的情况。 如果在防御上花费皇冠可以使怪物的伤害为零，那么答案是`0/1`。 否则，计算尽可能少的攻击次数并仅评估该选择。 
3. 对于正的初始攻击伤害，令`h`是所需的攻击次数。 最大可能`h`是没有攻击升级的攻击次数。 最优的`h`是边界值或接近损伤函数的连续版本达到最小值的点。 
4. 检查必要的候选值`h`。 对于每个候选者，计算所需的最小攻击升级，使用所有剩余的王冠进行防御，并计算收到的伤害的分数。 
5. 保留最小的分数并以简化形式打印。 

为什么有效：对于任何固定数量的攻击，在攻击上花费额外的皇冠无法提高回合数，因此最佳解决方案始终使用该回合数所需的最小攻击升级，并将其余的花费在防御上。 剩下的优化是一个单变量函数。 它的形状是单调的或凸的，因此通过检查边界及其驻点的邻域来捕获最小值。 

## Python 解决方案```python
import sys
from fractions import Fraction

input = sys.stdin.readline

def solve_case(ag, dg, ac, dc, n, m, a, b):
    base_attack = max(0, ag - dc)
    base_taken = max(0, ac - dg)

    def evaluate(k):
        need = Fraction(n, k)
        add_attack = max(Fraction(0), need - base_attack)
        remain = Fraction(m) - Fraction(a) * add_attack
        defense_gain = remain / b
        taken = max(Fraction(0), Fraction(base_taken) - defense_gain)
        return (k - 1) * taken

    if base_attack == 0:
        if b * base_taken < m:
            return Fraction(0)
        k = (n * a + m - 1) // m
        return evaluate(k)

    kmax = (n + base_attack - 1) // base_attack

    if kmax == 1:
        return Fraction(0)

    candidates = {1, kmax}

    last = kmax - 1
    if last >= 1:
        c = b * base_taken - b * m + a * base_attack
        t = a * n

        if c <= 0:
            candidates.add(last)
        else:
            root = int((t / c) ** Fraction(1, 2))
            for x in range(root - 3, root + 4):
                if 1 <= x <= last:
                    candidates.add(x)

    ans = None
    for k in candidates:
        if 1 <= k <= kmax:
            cur = evaluate(k)
            if ans is None or cur < ans:
                ans = cur

    return ans

def main():
    out = []
    t = int(input())
    for _ in range(t):
        ag, dg, ac, dc = map(int, input().split())
        n, m, a, b = map(int, input().split())

        ans = solve_case(ag, dg, ac, dc, n, m, a, b)
        out.append(f"{ans.numerator}/{ans.denominator}")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```功能`evaluate`是固定转动观察的直接平移。 它首先找到完成所需的最小攻击增加`k`攻击。 由于攻击和防御使用相同的皇家预算，因此剩余的资金总是转换为防御。 

零攻击情况被分开，因为可能的攻击数量不受原始统计数据的限制。 当防御可以完全消除时，使用微小的攻击升级和多次攻击可以使受到的伤害为零。 

对于积极的攻击伤害，`kmax`是没有购买攻击的攻击次数。 任何数量的攻击都不可能是最佳的，因为升级只会增加攻击。 候选搜索使用剩余函数的凸形式并仅检查接近数学最小值的值。`Fraction`仅用于最终的一小组候选人。 它避免了浮点错误，同时保持较短的运行时间。 Python 整数还安全地处理所有中间值。

 ## 边缘情况

 当杰洛特以零攻击伤害开始时，算法永远不会尝试枚举攻击计数。 它检查防御是否可以达到零伤害。 如果可以，答案为零，因为杰洛特可以在攻击上花费任意少量的资金，而将其余的资金用于防御。 

当杰洛特一次攻击杀死怪物时，乘数`(k - 1)`变为零。 该实现保持了这个精确的条件，因此它不会意外地计算出最终的怪物攻击。 

当最优升级需要分数时，每次计算都保留为有理数。 最后的分数由 Python 自动减少`Fraction`，避免四舍五入的十进制值产生的错误。
