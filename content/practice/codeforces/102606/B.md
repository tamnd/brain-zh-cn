 ## 解决方案
 ## 问题理解

 该问题是关于发现隐藏的二进制字符串。 我们只知道它的长度。 唯一可用的信息来自查询：我们提交另一个二进制字符串，判断器告诉我们提交的字符串是否作为子序列出现在隐藏字符串中。 

挑战在于隐藏字符串的长度可达 1000，而每个查询的长度被限制为该长度的大约一半。 询问整个已知前缀的直接重建方法最终会产生太长的查询。 解决方案必须使用查询长度限制作为指导。 

因为最多有 1024 个查询，`n`最多 1000 个，每个字符使用大约一个查询的方法是可以接受的。 然而，任何需要对可能的字符串进行二次探索的解决方案都是不可能的，因为可能的二进制字符串的数量呈指数增长。 

棘手的情况不是由大值引起的，而是由我们重建的方向引起的。 例如，如果隐藏字符串是：```
1
```唯一有效的答案是：```
1
```假设总是可以先测试零并盲目附加它的解决方案将会失败。 

对于小型拆分案例：```
n = 4
hidden = 0110
```如果我们尝试通过询问当前答案加上一个新字符是否是一个子序列来重构从左边开始的所有四个字符，那么在找到三个字符后，查询长度变为四个，这比允许的查询长度三大。 每个大字符串都会出现同样的问题。 正确的方法必须从两端进行重建，以便每个查询都保持在限制范围内。 

## 方法

 自然的暴力想法是从左到右构建答案。 假设我们已经知道一个前缀`p`。 我们可以问是否`p + "0"`是一个子序列。 如果不是，则下一个字符必须是`1`。 这是有效的，因为真实字符串的每个前缀本身就是隐藏字符串的子序列。 

问题是查询大小。 在发现大约一半的字符串后，下一个查询将包含已知的前缀加上一个字符，超出了允许的长度。 为了`n = 1000`，完整的从左到右重建需要长度接近 1000 的查询，而限制仅为 501。 

关键的观察结果是限制恰好是长度的一半。 我们可以从左边重建前半部分，从右边重建后半部分。 从右侧重建时，我们将已知的后缀保留在查询末尾，并在前面添加一个候选字符。 查询长度永远不会超过字符串的一半加一。 

两半一起覆盖每个位置，查询次数最多为`n`，很容易符合限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了|
 | 从左到右重建 | O(n) 次查询，但查询大小无效 | O(n) | 不允许|
 | 双面重建| O(n) 次查询 | O(n) | 已接受 |

 ## 算法演练

 1. 让`half = n // 2`。 重建第一个`half`从左到右的字符。 维护已找到的前缀。 询问前缀后面是否有`0`是一个子序列。 如果答案是肯定的，则下一个字符是`0`; 否则它一定是`1`。 

本阶段最长的查询有长度`half`，因此它尊重查询限制。 

1. 从右到左重构剩余的字符。 保留已找到的后缀。 询问是否`0`当前后缀后面是一个子序列。 如果是，则新角色是`0`; 否则就是`1`。 

添加新字符之前的后缀长度永远不会超过`n - half - 1`，所以查询长度最多为`half + 1`。 

1. 将重构后的后缀反转并放置在前半部分之后。 这两部分一起形成原始字符串。 

为什么它有效：

 第一阶段的不变性是存储的前缀与隐藏字符串的对应前缀完全相同。 添加任一`0`或者`1`创建隐藏字符串的候选前缀，并且只有正确的前缀才保留为子序列。 

第二阶段从相反的方向使用相同的想法。 当下一个真实字符放在隐藏字符串之前时，隐藏字符串的正确后缀仍然是子序列。 测试`0 + suffix`区分下一个字符是零还是一。 由于每个位置恰好属于两个重建部分之一，因此最终的字符串是正确的。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def ask(s):
    print("? " + s, flush=True)
    return int(input())

n = int(input())

half = n // 2

left = ""
for _ in range(half):
    if ask(left + "0"):
        left += "0"
    else:
        left += "1"

right = ""
for _ in range(n - half):
    if ask("0" + right):
        right = "0" + right
    else:
        right = "1" + right

print("! " + left + right, flush=True)
```功能`ask`处理交互式通信。 每个查询都会立即刷新，因为交互式判断会在回复之前等待程序的输出。 

第一个循环构建左侧部分。 在每一点，当前前缀都已知是正确的，因此检查下一个零就足够了。 相反的情况必须是一种，因为隐藏字符串在该位置只有一个字符。 

第二个循环使用相同的逻辑，但向后增长答案。 作业`right = "0" + right`在从右向左添加字符时保持后缀的顺序正确。 

不需要超出分割点的整数计算，因此不存在溢出问题。 重要的边界是查询长度，两个循环的设计使得最大查询大小为`floor(n/2)+1`。

 ## 边缘情况

 对于单字符字符串`1`，第一阶段没有要重建的字符，因为`n // 2`为零。 后缀阶段询问是否`0`是可能的。 答案是假的，所以算法将`1`后缀并返回正确的字符串。 

对于偶数长度的字符串，例如`0110`，分割创建两个大小相等的部分。 左相仅处理`01`，右边的相位手柄`10`。 双方都不需要超过三个字符的查询，这是该长度允许的限制。 

对于奇数长度的字符串，例如`10101`，左侧部分的长度为 2，右侧部分的长度为 3。 正确的重建仍然有效，因为在添加每个字符之前，存储的后缀足够短，以至于在前面添加一个字符可以使查询保持在限制之内。 最终的串联保留了原始顺序。
