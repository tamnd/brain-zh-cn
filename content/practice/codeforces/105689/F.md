 ## 解决方案
 ## 问题理解

 该节日包含一排灯笼，每个灯笼都有一个当前高度。 龙从一个选定的灯笼开始，并希望最终站在每一个灯笼上。 只有当相邻灯笼当时的高度匹配时，才可能在它们之间进行跳跃。 

龙可以用他目前站立的灯笼的高度来交换能量。 将灯笼降低一处会产生一能量，而将灯笼增加一处会消耗一能量。 任务是回答许多问题：对于起始位置，所需的最小初始能量是多少，以及在一些问题之后，灯笼的高度可能会改变。 

输入描述了灯笼的数量和操作，然后是初始高度。 更新改变了灯笼的高度。 有一个问题询问给定灯笼指数的最小启动能量。 

限制很大，最多可达$2 \cdot 10^5$灯笼和$2 \cdot 10^5$运营。 这排除了扫描每个问题的所有灯笼，因为这需要大约$4 \cdot 10^{10}$最坏情况下的操作。 我们需要一个更新和查询都需要对数时间或常数时间的结构。 

棘手的部分是认识到龙不能通过反复降低和升起同一个灯笼来产生自由能量。 降低灯笼会产生能量，但随后将灯笼返回到下一跳所需的高度会消耗完全相同的能量。 唯一重要的是所参观的灯笼的相对高度。 

一个常见的错误是只考虑一个方向的下一个灯笼。 龙可能需要访问对面的一个非常高的灯笼，因此每个起始位置都必须考虑整排中最高的灯笼。 

例如，输入：```
3 1
5 1 2
1 2
```答案是：```
0
```从第一个灯笼开始已经具有最大高度，因此不需要初始能量。 

另一个边缘情况是起始灯笼不是最高的：```
3 1
5 1 2
1 2
```如果查询的是灯笼 2，则答案将是：```
4
```仅检查相邻灯笼的解决方案可能会错过另一端的高度 5 并返回较小的值。 

## 方法

 直接接近会模拟龙的动作。 从选定的灯笼开始，我们可以尝试左右移动，记录每一跳所需的能量。 这是有效的，因为可以准确地模拟运动规则。 然而，对于一个查询，它可能需要查看所有$n$灯笼。 和$q$查询，最坏的情况变成$O(nq)$，远远超出了允许的范围。 

关键的观察来自于观察跳跃期间的能量变化。 假设龙从高处的灯笼中移动$x$到邻近高度的灯笼$y$。 如果$y$越高，龙花$y-x$活力。 如果$y$越低，龙增益$x-y$活力。 在这两种情况下，能量的变化量如下：$$x-y$$经过一系列跳跃后，所有中间高度都消失。 从灯笼开始$p$并到达高处的灯笼$h$，能量变为：$$E + a_p - h$$当龙到达它所访问过的最高的灯笼时，能量最低。 由于目标是访问每个灯笼，因此最高的灯笼就是整个阵列中的最大高度。 

因此，位置所需的初始能量$p$是：$$\max(0, \text{maximum height} - a_p)$$我们唯一需要的动态信息是当前的最大高度。 更新可以更改该最大值，因此我们维护高度的多重集并在每次操作后检索最大值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每次查询 O(n)，总共 O(nq) | O(1) | O(1) | 太慢了|
 | 最佳 | 每次更新 O(log n)，每次查询 O(1) | O(n) | 已接受 |

 ## 算法演练

 1. 将每个灯笼高度存储在一个可以插入、删除和检索最大值的数据结构中。 具有延迟删除功能的最大堆足以解决此问题。 
2. 对于更新操作，将旧高度替换为新高度。 旧值无法直接从堆中删除，因此单独存储每个灯笼的当前高度，并在检查最大值时忽略过时的堆条目。 
3. 提灯问题$p$，首先删除过时的堆条目，然后取当前的最大高度。 答案是该最大值与起始灯笼高度之间的差值，如果差值为正，否则为零。 
4. 输出计算值。 

为什么有效：在任何跳跃过程中，龙的能量都会根据当前灯笼的高度和下一个灯笼的高度之间的差异而变化。 在一条完整的路线上，所有访问过的中间高度都会抵消。 唯一的危险点是访问最高的灯笼，因为与起始高度相比，那是龙消耗最多能量的地方。 有足够的能量达到这个高度意味着其他所有灯笼也可以被参观。 该公式精确地测量了使起始灯笼与最高灯笼一样高所需的缺失能量。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    heap = []
    for i, x in enumerate(a):
        heapq.heappush(heap, (-x, i))

    out = []

    for _ in range(q):
        query = input().split()
        if query[0] == '1':
            p = int(query[1]) - 1
            while -heap[0][0] != a[heap[0][1]]:
                heapq.heappop(heap)
            out.append(str(max(0, -heap[0][0] - a[p])))
        else:
            p = int(query[1]) - 1
            x = int(query[2])
            a[p] = x
            heapq.heappush(heap, (-x, p))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```数组`a`存储每个灯笼的当前高度。 这是必需的，因为堆条目在更新后可能会变得陈旧。 

堆存储负高度，因为 Python 的堆是最小堆。 因此，最大高度位于顶部，作为最小的负数。 

在回答查询之前，代码会删除不再与当前高度匹配的堆条目`a`。 这种惰性删除避免了对更复杂的数据结构的需要，同时保持所有操作的快速。 

查询答案直接使用推导公式。 这`max`调用处理起始灯笼已经具有全局最大高度的情况，因为龙不需要任何初始能量。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 每次更新 O(log n)，每次查询摊销 O(1) | 每次更新都会插入一个堆条目，并且过时的条目最多会被删除一次 |
 | 空间| O(n + q) | 堆可能包含来自更新的旧条目 |

 约束条件允许$2 \cdot 10^5$运算，因此需要对数更新结构。 堆解决方案保持在限制范围内，因为每个堆元素都被推送一次并被删除一次。

 ## 边缘情况

 当只有一盏灯笼的时候，龙已经巡遍了每一盏灯笼。 对于输入：```
1 1
7
1 1
```最大高度和起始高度都是7，所以答案是：```
0
```该算法可以处理这个问题，因为所需的能量是最大高度和起始高度之间的正差。 

当起始灯已经最高时，不需要初始能量。 为了：```
3 1
5 2 4
1 1
```最大高度是5，起始高度也是5。答案是：```
0
```龙可以在调整其他灯笼时获得或消耗能量。 

当高度更新删除之前的最大值时，过时的堆值不得影响答案。 为了：```
2 3
100 0
2 1 10
1 2
1 1
```更新后高度为`[10, 0]`。 旧值`100`暂时保留在堆内，但延迟删除步骤会在应答之前将其删除。 答案是：```
10
0
```因为当前的最大值是 10，而不是过时的值 100。
