 ## 解决方案
 # 问题理解

 舞龙队伍已经有了固定的顺序。 詹姆斯可能会移除一些舞者，但留下来的舞者仍然必须尊重原来的“谁站在谁后面”的关系。 舞者只能将原队列中紧邻其前面的人保留在原队列中，除非该舞者成为新队列中的第一个舞者。 

这意味着所选的舞者必须形成原始队列的一个连续片段。 如果我们跳过中间的一个舞者，下一个选择的舞者将被迫站在新的舞者后面，这是不允许的。 

剩下的要求是该段中相邻舞者的身高必须足够接近。 对于所选片段中的每对连续舞者，他们身高之间的绝对差不得超过`k`。 任务是找到这样一个连续段的最大长度。 

输入包含舞者数量、允许的最大身高差以及舞者原始顺序的身高。 输出是有效舞龙中可以保留的最大舞者数量。 

舞者人数可达`2 * 10^5`，因此检查每个可能的段的算法是不切实际的。 有大约`n^2 / 2`可能的部分，大约是`2 * 10^10`在最坏的情况下进行检查。 解决方案必须在大致线性的时间内处理该线路。 

主要的边缘情况来自于将问题视为一般子序列问题而不是连续段问题。 例如，考虑：```
5 1
1 10 2 3 4
```正确的输出是：```
3
```有效段是`2 3 4`。 粗心的方法可能会选择`1 2 3 4`通过跳过`10`，但这会违反原来的顺序关系，因为 dancer`2`现在会站在不同的人后面。 

另一种情况是每个相邻对都有效：```
4 100
5 6 7 8
```答案是：```
4
```算法不得提前停止或错误地要求段具有恰好某个最小大小。 

最终的边界情况是：```
1 0
42
```答案是：```
1
```单个舞者始终是有效的舞龙，因为没有相邻的舞者可以违反高度条件。 

## 方法

 一种直接的方法是尝试每一个可能的起始舞者，并将该段向右延伸，直到高度差变得太大。 对于每个起始位置，我们可以扫描几乎所有剩余的舞者。 这是正确的，因为它检查每个可能的连续段，但在最坏的情况下，它的性能约为`n * (n + 1) / 2`比较。 和`n = 200000`，大致就是`2 * 10^10`操作，远远超出了时间限制。 

问题的结构给了我们一个更简单的视角。 当一个段内的每个相邻对都有效时，该段才有效。 从左向右扫描时，如果当前舞者能够站在前一个舞者的后面，则可以延长当前有效片段。 如果高度差太大，则以当前舞者结束的片段不能包含前一个舞者，因此当前舞者必须开始新的片段。 

这将问题转变为维护当前有效后缀的长度，同时跟踪迄今为止看到的最佳答案。 每个舞者都被处理一次，因此解决方案变得线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取舞者数量、允许的最大身高差以及身高数组。 

2. 从当前段长度开始`1`以及最佳答案`1`。 单个舞者总是形成有效的队列。 

3. 从第二个位置开始扫描舞者。 将当前舞者的身高与前一个舞者的身高进行比较。 

4.如果绝对差最多为`k`，通过增加当前段的长度来扩展当前段。 这是有效的，因为新舞者可以直接站在前一个舞者的后面。 

5. 如果差异大于`k`，当前舞者不能留在同一段。 开始一个仅包含该舞者的新片段。 

6. 每次更新后，将当前段长度与最佳答案进行比较，并保留最大值。 

这样做的原因是，有关段所需的唯一信息是其最后一个相邻对是否有效。 如果一对舞者违反了规则，则包含两个舞者的每个片段都是无效的，因此以当前舞者结束的唯一可能的有效片段必须从当前舞者或更晚的时间开始。 维护的段始终是在当前位置结束的最长有效段，这意味着扫描期间找到的最大值就是全局答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    h = list(map(int, input().split()))

    ans = 1
    cur = 1

    for i in range(1, n):
        if abs(h[i] - h[i - 1]) <= k:
            cur += 1
        else:
            cur = 1
        if cur > ans:
            ans = cur

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案仅保留两个计数器。`cur`表示以当前舞者结束的有效片段的长度。`ans`存储遇到的最大段长度。 

循环从索引处开始`1`因为第一个舞者没有之前的舞者可以比较。 当相邻高度差可接受时，当前段增长。 否则，之前的舞者不能再成为此处结束的有效片段的一部分，因此计数器重置为 1。 

不使用超出数组边界的索引，因为扫描仅访问`i`和`i - 1`后`i`已达到`1`。 Python 整数还可以安全地处理大高度值，而无需担心溢出。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 |---|---|---|
 | 时间 | O(n) | 每个舞者都会被拜访一次。 |
 | 空间| O(1) | O(1) | 读取高度后仅存储计数器。 |

 线性运行时间适用于`n = 200000`因为算法只为每个舞者执行少量恒定的工作。 除了存储输入数组之外，内存使用量也很少。 

## 测试用例```python
import sys
import io

def solve_data(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n, k = map(int, sys.stdin.readline().split())
    h = list(map(int, sys.stdin.readline().split()))

    ans = 1
    cur = 1

    for i in range(1, n):
        if abs(h[i] - h[i - 1]) <= k:
            cur += 1
        else:
            cur = 1
        ans = max(ans, cur)

    sys.stdin = old_stdin
    return str(ans)

assert solve_data("7 4\n1 2 1 2 6 7 1\n") == "6"
assert solve_data("6 3\n7 4 7 4 8 9\n") == "4"

assert solve_data("1 0\n42\n") == "1"
assert solve_data("5 1\n1 10 2 3 4\n") == "3"
assert solve_data("4 100\n5 6 7 8\n") == "4"
assert solve_data("5 0\n9 9 8 8 8\n") == "3"
```| 测试输入| 预期产出 | 它验证了什么 |
 |---|---|---|
 |`1 0 / 42`|`1`| 一名舞者的最小尺寸输入 |
 |`5 1 / 1 10 2 3 4`|`3`| 防止将答案视为任意子序列 |
 |`4 100 / 5 6 7 8`|`4`| 所有相邻对均有效 |
 |`5 0 / 9 9 8 8 8`|`3`| 检查精确的相等边界和段重置 |

 ## 边缘情况

 对于单个舞者的情况：```
1 0
42
```该算法初始化两者`cur`和`ans`到`1`。 循环永远不会运行，所以答案仍然存在`1`，这与一个舞者总是形成有效队列的事实相匹配。 

对于跳过舞者陷阱：```
5 1
1 10 2 3 4
```扫描从长度开始`1`。 之间的区别`1`和`10`太大，因此该段重置为`10`。 之间的区别`10`和`2`也重置它。 最终三位舞者各有不同`1`和`1`，给出有效的长度段`3`。 该算法永远不会错误地连接分开的舞者。 

对于所有有效的情况：```
4 100
5 6 7 8
```每个相邻的差值都小于`100`，因此当前长度从`1`到`4`。 答案就变成了`4`，表明该算法可以不断扩展一段直到结束。 

对于有严格限制的重复值：```
5 0
9 9 8 8 8
```第一对`9`s 有效，给出长度`2`。 这对`9`和`8`中断该段，因此扫描从第一个开始`8`。 最后三名`8`s 形成答案，给出`3`。 这会检查重置是否恰好发生在无效的相邻对上。
