 ## 解决方案
 ## 问题理解

 我们维护着多组怪物。 怪物仅通过其当前 HP 进行识别，并且查询会更改具有特定 HP 值的怪物数量，或者询问如果两个玩家都处于最佳状态，需要多少次 Bob 回合才能移除给定数量的怪物。 

游戏的关键数量不是攻击的确切顺序，而是必须消除的生命值。 考虑一只具有 HP 的怪物`x`。 爱丽丝总是先行动，并且可以在每次鲍勃攻击之前使该怪物增加 1 点。 后`t`鲍勃的攻击集中在这个怪物身上，它收到`t`增加并且`2t`造成伤害，所以剩余HP为`x + t - 2t = x - t`。 它恰好在什么时候消失`t = x`。 这意味着一只具有 HP 的怪物`x`成本正好`x`鲍勃转身要移开。 

对于多个怪物，同样的想法也适用。 如果Bob选择了一些总HP的怪物`S`，他正好可以花费`S`轮流将它们移除。 原因是鲍勃每回合贡献2点伤害，而爱丽丝只贡献1点生命值，所以一整轮会减少所选怪物的总生命值1。 鲍勃总是可以攻击爱丽丝刚刚增加的怪物，防止爱丽丝在单个怪物身上积累额外的生命值。 Alice 不能将整个过程延迟到超出初始 HP 值之和。 

由于鲍勃想尽快完成，他选择了HP值最小的怪物。 一个查询要求`k`因此，死亡人数要求求总和`k`当前存在的最小 HP 值。 

查询数量可达`3 * 10^5`，因此为每个查询扫描所有怪物是不可能的。 HP 值的界限为`10^6`，这意味着我们可以存储由 HP 索引的信息。 每次更新后对所有怪物进行排序的解决方案会太慢，因为怪物的数量也会变得非常大。 我们需要一种对数数据结构，支持改变一个HP值的计数并找到包含给定数量怪物的前缀。 

重要的边缘情况集中在重复的 HP 值和边界位置周围。 查询可以询问具有一个 HP 值的所有怪物，也可以在具有相同 HP 值的一组中间停止。 

例如：```
5
1 3 4
2 2
1 3 1
2 3
2 4
```第一次更新后有四个 HP 3 的怪物。第一个查询要求两个怪物，所以答案是`6`，因为两个最小的 HP 值是`3`和`3`。 

输出是：```
6
10
13
```如果粗心地只存储不同的 HP 值而忽略它们的多重性，则会失败，因为一个 HP 值可以代表许多怪物。 

另一种边界情况是当请求时`k`恰好在值边界处结束。```
2
1 1 5
2 5
```答案是`25`。 当前缀计数恰好达到时，数据结构必须包括整个频率块`k`。 

## 方法

 直接方法会将每个怪物存储在一个列表中。 对于类型 2 查询，我们可以对当前 HP 值进行排序，取第一个`k`，然后添加它们。 这是正确的，因为游戏简化为选择`k`最小 HP 值。 然而，最多可以有`3 * 10^5`查询，怪物数量可达左右`10^11`因为每次更新最多可以设置一个计数`10^6`。 即使忽略排序成本，迭代所有怪物也是不可能的。 每次查询后排序都会远远超出时间限制。 

有用的观察是 HP 值本身很小。 我们不需要单独了解每个怪物。 对于每个 HP 值，我们只需要两条信息`x`：有多少怪物有HP`x`，以及这些怪物的总贡献，即`x * count[x]`。 

这将问题转化为在固定坐标范围内维持频率和加权和。 芬威克树是一种自然的选择，因为更新会影响一个位置，而查询需要前缀和。 一棵芬威克树存储计数，另一棵存储生命值总和。 为了回答查询，我们找到前缀计数达到的最小 HP 值`k`。 所有较小的值都被完全取走，剩余的怪物则从最终的HP值中取走。 

比较是：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(M log M)`每个查询，其中`M`是怪物的数量|`O(M)`| 太慢了|
 | 芬威克树 |`O(log 10^6)`每个查询 |`O(10^6)`| 已接受 |

 ## 算法演练

 1. 存储两棵按 HP 索引的 Fenwick 树。 第一棵树存储每个 HP 值存在多少怪物。 第二棵树存储了该值贡献的总HP，因此位置`x`商店`x * count[x]`。 
2. 对于更新查询，更改具有 HP 的怪物数量`x`到`y`，计算与先前计数的差值。 将此差异添加到计数芬威克树并添加`x`将此差值乘以 Fenwick 树之和。 
3. 对于要求第一个的查询`k`按HP顺序排列的怪物，使用计数芬威克树找到最小的HP值`pos`其中前缀计数至少变为`k`。 
4.所有HP值小于`pos`都完全包含在内。 将芬威克树的总生命值相加。 
5.剩余需要的怪物从HP中取出`pos`。 将剩余数乘以`pos`并将其添加到答案中。 

这样做的原因是答案仅取决于 HP 值的排序多重集。 芬威克树让我们可以导航这个排序顺序，而无需显式存储每个怪物。 

### 为什么它有效

 在每轮完整的爱丽丝-鲍勃回合之后，如果鲍勃在该集合内进行攻击，则任何选定的怪物集合的总生命值都会减少一倍。 鲍勃总是可以选择他的攻击，以便他想要消除的怪物受到必要的伤害，而爱丽丝的额外生命值每轮只会取消一点进度。 因此，怪物的总HP的集合`S`准确地要求`S`鲍勃转身消失。 

鲍勃希望其中的总 HP 尽可能最小`k`怪物，所以最优选择正是`k`最小 HP 值。 数据结构精确地返回这个总和，这证明算法产生了正确的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXX = 10**6

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, idx, val):
        while idx <= self.n:
            self.bit[idx] += val
            idx += idx & -idx

    def sum(self, idx):
        res = 0
        while idx:
            res += self.bit[idx]
            idx -= idx & -idx
        return res

    def kth(self, k):
        idx = 0
        step = 1 << (self.n.bit_length() - 1)
        while step:
            nxt = idx + step
            if nxt <= self.n and self.bit[nxt] < k:
                idx = nxt
                k -= self.bit[nxt]
            step >>= 1
        return idx + 1

def solve():
    q = int(input())
    cnt_tree = Fenwick(MAXX)
    sum_tree = Fenwick(MAXX)
    cnt = [0] * (MAXX + 1)

    ans = []

    for _ in range(q):
        query = input().split()
        t = int(query[0])

        if t == 1:
            x = int(query[1])
            y = int(query[2])
            diff = y - cnt[x]
            cnt[x] = y
            cnt_tree.add(x, diff)
            sum_tree.add(x, diff * x)

        else:
            k = int(query[1])
            pos = cnt_tree.kth(k)
            before = cnt_tree.sum(pos - 1)
            total = sum_tree.sum(pos - 1)
            total += (k - before) * pos
            ans.append(str(total))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```这`cnt`数组存储当前每个HP值的频率，以便更新可以转换为差异。 分域树仅存储查询所需的聚合信息。 

这`kth`函数在 Fenwick 树上执行二元提升。 它找到前缀计数达到请求的第一个位置`k`。 这避免了具有重复前缀查询的二分搜索，并使每个查询保持对数。 

答案计算将完全包含的前缀与最终部分包含的 HP 值分开。 这是通常出现相差一错误的地方。 之前的计数`pos`必须被排除，并且仅`k - before`怪物来自`pos`贡献。 

Python 整数可以处理最大可能的和而不会溢出。 最大可能的贡献远高于 32 位限制，因此使用普通的 Python 算术可以避免任何额外的处理。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(Q log 10^6)`| 每次更新、前缀查询和第 k 个搜索都使用 Fenwick 树操作 |
 | 空间|`O(10^6)`| 两棵Fenwick树和频率数组由HP索引 |

 最大HP值固定为`10^6`，所以对数因子约为 20。`3 * 10^5`查询时，该解决方案仅执行几百万次 Fenwick 操作，完全符合限制。

 ## 边缘情况

 当所有怪物HP相同时，第k小的搜索直接落在一个频率块上。 例如：```
3
1 7 4
2 3
2 4
```答案是：```
21
28
```芬威克树不需要针对单个怪物单独的条目。 它在位置 7 处看到四个怪物，并从该方块中获取所需的数量。 

当更新移除特定HP的所有怪物时，频率差变为负值。 例如：```
4
1 3 5
1 3 0
1 2 4
2 4
```最终的答案是：```
8
```更新正确地减去了之前贡献的HP 3，只剩下四只怪物的HP 2。 

当`k`正好在频率块的末尾结束，第 k 个搜索必须返回该块而不是下一个。 例如：```
3
1 2 3
1 5 3
2 3
```答案是：```
6
```前三个怪物的 HP 都是 2，因此搜索在位置 2 处停止。该实现处理此问题是因为`kth`查找第一个前缀，其计数至少为`k`，不严格大于`k`。
