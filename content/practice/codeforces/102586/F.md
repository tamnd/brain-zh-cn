 ## 解决方案
 ## 问题理解

 我们在数轴上有两组已排序的点。 第一组包含机器人位置，第二组包含天线位置。 每次我们激活天线时，它都会删除距离最近的仍然活着的机器人，并支付它们之间的距离。 任务不是直接决定最终的匹配，而是选择天线激活的顺序，使得所有付费距离的总和尽可能小。 

输出有两部分。 第一行是可能的最小总距离。 第二行是达到该值的所有天线的激活顺序。 

机器人的数量可以多达 200000 个。在最坏的情况下，二次解将执行大约 40000000000 次操作，这远远超出了两秒所允许的极限。 我们需要一种接近线性或线性时间的算法。 坐标可以大到 10^9，因此实现必须使用 64 位整数来表示距离。 

有几个细节可能会破坏原本合理的解决方案。 首先，最近的机器人在每次激活后都会发生变化。 例如，机器人位于 0 和 10 处，天线位于 4 和 6 处，激活天线 4 首先会移除 0 处的机器人，但之后天线 6 被迫接收 10 处的机器人。预先计算所有最近的机器人一次的解决方案将是错误的。 

第二个问题是平局规则。 如果天线恰好位于两个机器人的中间，则左侧机器人就会消失。 例如，机器人位于 0 和 10，天线位于 5，则所选机器人为 0，而不是 10。忽略此规则可能会更改结果顺序。 

第三个问题是答案需要订单，而不仅仅是最低金额。 单独的最小成本匹配算法并不能描述有效的激活序列。 

## 方法

 直接方法会模拟该过程并重复搜索接下来应该激活的天线。 如果我们尝试每一个可能的下一个天线，并通过扫描所有机器人找到离它最近的剩余机器人，那么复杂度就变成了 O(N^3)。 如果我们检查每个可能的激活选择，即使使用二分搜索改进最近的机器人搜索，仍然会留下 O(N^2) 的方法。 

关键的观察结果是，最好的下一步行动始终是当前最接近的机器人天线对。 假设剩余的最近对的距离为 d。 如果我们先激活其他天线，其成本至少为 d。 移除其他天线并不能使所选的最接近的一对更便宜，因为所选的机器人和天线仍然存在。 立即激活最接近的一对现在可以支付尽可能小的金额，并将相同类型的问题留给较小的集合。 重复这个贪婪的选择给出了一个最优序列。 

剩下的挑战是有效地保持最接近的相反颜色对。 在一维中，最近的机器人和天线必须按照所有剩余点的排序顺序相邻。 如果它们之间还有另一个点，该点将与两个点之一创建一个更短的交叉颜色对。 这意味着我们只需要在合并列表中维护相邻对。 

当一对被删除时，只能出现一个新的邻接：被删除的对之前的点和它之后的点。 我们可以将所有候选相邻对存储在优先级队列中，并仅更新这些本地更改。 这将整个过程减少到 O(N log N)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N^3) | O(N^3) | O(N) | 太慢了|
 | 最佳| O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

1. 将所有机器人和天线合并到一个已排序的数组中。 存储每个元素的坐标、类型和原始天线索引（如果它是天线）。 该数组的顺序表示数轴上幸存点的当前顺序。 
2. 对于此合并数组中的每个相邻对，如果一个元素是机器人，另一个是天线，则将该对及其距离插入到最小堆中。 这些正是一开始可能最接近的对。 
3. 重复从堆中取出最小距离对。 如果其中一个元素已被删除或者这两个元素不再是邻居，则丢弃它并继续。 否则，这是下一个贪婪激活。 
4. 将这一对的距离添加到答案中，并将天线索引附加到输出顺序中。 从幸存点的链表中删除天线和机器人。 
5. 删除一对后，将其前一个幸存邻居与其下一个幸存邻居连接。 如果这两个新邻居具有不同的类型，则将这个新的候选对插入到堆中。 
6. 继续，直到每个天线都被激活。 收集到的天线索引是所需的阶数。 

贪婪选择起作用的原因是当前最小的机器人天线距离是不可避免的。 至少一个天线激活必须支付该金额或更多，因为该对是所有剩余点之间可能最接近的相互作用。 首先采用它可以达到这个下界，并且使相同的问题少两个点。 通过归纳，后面的每一步也是最优的。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    points = []
    for i, x in enumerate(a):
        points.append((x, 0, -1))
    for i, x in enumerate(b):
        points.append((x, 1, i + 1))

    points.sort()

    m = 2 * n
    left = [-1] * m
    right = [-1] * m
    for i in range(m):
        if i:
            left[i] = i - 1
        if i + 1 < m:
            right[i] = i + 1

    def add_pair(u, v):
        if u == -1 or v == -1:
            return
        if points[u][1] != points[v][1]:
            heapq.heappush(heap, (points[v][0] - points[u][0], u, v))

    heap = []
    for i in range(m - 1):
        add_pair(i, i + 1)

    ans = 0
    order = []

    while order.__len__() < n:
        while True:
            d, u, v = heapq.heappop(heap)
            if right[u] == v and left[v] == u:
                break

        ans += d
        if points[u][1] == 1:
            order.append(points[u][2])
        else:
            order.append(points[v][2])

        l = left[u]
        r = right[v]

        if l != -1:
            right[l] = r
        if r != -1:
            left[r] = l

        add_pair(l, r)

    print(ans)
    print(*order)

if __name__ == "__main__":
    solve()
```合并后的数组一开始就排序一次。 数组`left`和`right`充当此排序顺序的链接列表。 从普通的 Python 列表中删除元素会太慢，因为每次删除可能会移动许多元素。 

堆存储候选相邻对。 有些条目在稍后删除后会变得无效，因此代码会进行检查`right[u] == v and left[v] == u`在使用一对之前。 这种惰性删除避免了昂贵的堆更新。 

距离计算使用 Python 整数，它可以安全地处理最多大约 2 * 10^14 的可能总距离。 天线索引与其坐标分开存储，因此最终输出使用原始编号。

 ## 边缘情况

 第一个边缘情况是改变最近的机器人。 用于输入```
2
0 10
4 6
```第一次激活以成本 4 删除 0 处的机器人。然后剩余的天线以成本 4 删除 10 处的机器人。该算法处理此问题是因为它在每次删除后更新合并链表，而不是保留陈旧的最近邻居信息。 

第二个边缘情况是平局。 用于输入```
2
0 10
5 20
```天线 5 选择机器人 0，因为联系向左。 合并顺序存储精确的坐标顺序，因此相邻对表示保留正确的选择。 

第三种边缘情况是删除一对会创建一个新的最接近的对。 用于输入```
3
0 50 100
10 90 200
```当第一个接近的点被移除后，被它分开的两个点可能会成为邻居。 链表更新后，堆立即接收这个新候选者，因此下一个贪婪选择仍然是正确的。
