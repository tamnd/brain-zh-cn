 ## 解决方案
 ## 问题理解

 我们得到一串小写英文字母。 目标是将其转换为一个字符串，其中从左到右读取时字符永远不会减少，这意味着每个字符按字母顺序至少与前一个字符一样大。 

我们可以任意改变字符。 每次更改都算作一次操作，我们希望最大限度地减少更改的字符数，同时仍以非递减的字符串结束。 

输出是双重的。 首先，我们报告必须修改的最少位置数。 其次，我们构造任何达到此最小值的有效非递减字符串。 

n 高达 200,000 的约束迫使我们远离任何二次策略。 任何尝试考虑所有可能的目标字符串或单独修复违规的所有可能方法的解决方案都会太慢。 我们需要本质上是线性或线性对数的东西。 

一个关键的微妙之处是，我们没有被要求尽可能在本地保留字符。 像“修复你所看到的每一个反转”这样的贪婪的局部修复可能会在全局范围内失败，因为修复一个位置可能会迫使以后进行额外的更改。 

一个简单的失败案例是像“cba”这样的字符串。 本地修复可能会将“cb”变成“cc”，然后变成“cca”，但这并不是最小的。 最好的解决方案是“bbb”或“ccc”，两者都只需要两次更改，但天真的贪婪修复可能会超出计数。 

另一个微妙的情况是，大块已经排序，但被几个字母稍微打乱。 例如“abzab”。 最佳解决方案可能涉及将整个字符串与仔细选择的最终结构对齐，而不是修复局部反转。 

## 方法

 蛮力的想法是将最终的字符串视为字母表上的某个非递减序列。 由于只有 26 个字母，我们可以想象在最终字符串已排序的约束下尝试所有可能的字母位置分配。 

直接的暴力解释是：选择任何长度为 n 的非递减字符串并计算有多少位置与原始位置不同。 非递减字符串的数量在n中呈指数增长，因为每个位置都可以保持不变或增加，所以这是完全不可行的。 即使限制字母选择也无济于事，因为长度为 n 超过 26 个字母的弱递增字符串的数量在组合上仍然是巨大的。 

我们需要不同的观点。 我们没有直接构造最终的字符串，而是翻转视角：对于字母表中的每个字母，决定到该点为止将分配给字母的位置数。 同样，我们考虑将字符串划分为 26 个连续的块，其中每个块对应一个固定的字母，并且块按字母顺序递增出现。 

这是关键结构：任何超过小写字母的非递减字符串都可以看作是由 26 个段组成的序列，其中第 i 段由字母“a”+ i 填充。 有些段可能是空的。 因此，任务变成选择这些段边界的位置，并为每个选择计算有多少原始字符与指定的字母匹配。 

我们可以预先计算每个字母在每个前缀或范围中出现的次数，以便对于固定分区，我们可以快速评估我们保留了多少个字符。 最佳答案是最大化保留字符的分区，答案是 n 减去该值。 

这将问题转化为超过 26 个状态的动态规划。 我们按顺序迭代字母并决定每个字母的段延伸多远。 因为只有 26 个字母，所以我们可以预先计算贡献并有效地评估转换。 该结构足够小，具有前缀计数的字母表状态上的 DP 就足够了。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对所有字符串进行暴力破解 | 指数| O(n) | 太慢了 |
 | 字母段上的 DP | O(26² + n·26) | O(26² + n·26) | O(n·26) 或 O(n) 优化 | 已接受 |

 ## 算法演练

 我们将最终的字符串重新解释为由 26 个有序相组成。 第 k 阶段将一些位置分配给字母“a”+ k，一旦我们进入后面的阶段，我们就再也不会回到更小的字母。 

为了精确计算，我们计算前缀计数，以便我们可以快速知道任何段中有多少字符与所选字母匹配。 

然后，我们构建一个动态编程状态，在其中决定按顺序将字符串中的多少个字符分配给每个字母。 

步骤1：预先计算前缀频率表。 对于每个位置 i 和每个字母 c，我们存储 c 在 s[0..i-1] 中出现的次数。 这允许 O(1) 查询任意时间间隔内的计数。 

步骤 2：将 dp[k][i] 定义为使用前 k 个字母（'a' 到 'a'+k-1）来覆盖字符串长度为 i 的前缀时可以保持正确匹配的最大字符数。 这意味着我们将前 i 个字符分配给 k 个非递减字母块。 

步骤 3：通过确定第 k 个字母块的结束位置来进行转换。 如果将第 k 个字母分配给位置 [j, i)，则所有这些位置都成为字母（第 k 个字母），贡献的匹配数就是该字母在该区间内出现的次数。 

我们尝试所有可能的 j < i，并采取最佳过渡。 这就是前缀和使计算速度更快的地方。 

步骤 4：答案是 dp[25][n]，代表我们可以使用整个字符串的所有 26 个字母来完成的最佳操作。 最少替换次数是 n 减去该值。 

步骤 5：为了重建结果字符串，我们存储指示哪个分割给出最佳值的父指针。 然后我们逐段分配字母。 

工作原理：任何有效的非递减字符串都唯一对应于将字符串划分为最多 26 个连续段，每个段都有一个常量字母，并且字母按段索引递增。 DP 探索所有此类分区并选择一个最大化保留匹配的分区。 由于每个有效的目标字符串都可以用这种形式表示，并且每个转换都保持单调性，因此不会错过最佳解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    # prefix counts: pref[i][c]
    pref = [[0] * 26 for _ in range(n + 1)]
    for i in range(n):
        for c in range(26):
            pref[i + 1][c] = pref[i][c]
        pref[i + 1][ord(s[i]) - 97] += 1

    # dp[k][i] = best matches using first k letters on prefix i
    dp = [[-10**9] * (n + 1) for _ in range(26)]
    parent = [[-1] * (n + 1) for _ in range(26)]

    # base: using 'a' only
    c0 = 0
    for i in range(n + 1):
        dp[0][i] = pref[i][0]

    for k in range(1, 26):
        for i in range(n + 1):
            best = -1
            best_j = -1
            for j in range(i + 1):
                # assign s[j:i] to letter k
                cnt = pref[i][k] - pref[j][k]
                val = dp[k - 1][j] + cnt
                if val > best:
                    best = val
                    best_j = j
            dp[k][i] = best
            parent[k][i] = best_j

    # reconstruct
    res = list(s)
    k = 25
    i = n

    while k >= 0:
        j = parent[k][i] if k > 0 else 0
        if k == 0:
            j = 0
        for x in range(j, i):
            res[x] = chr(97 + k)
        i = j
        k -= 1

    kept = dp[25][n]
    print(n - kept)
    print("".join(res))

if __name__ == "__main__":
    solve()
```该解决方案构建了一个前缀频率表，以便计算任何段中有多少个字符与给定字母匹配成为常数时间。 然后，动态编程以递增的顺序逐步将段分配给字母。 

一个微妙的实现细节是 dp 状态的初始化。 使用较大的负值可以避免意外选择未初始化的转换。 另一个细节是重构：我们从字母“z”向后走到“a”，以相反的顺序填充段，这保证了与 DP 决策的一致性。

 ## 边缘情况

 像“edcba”这样的完全递减的字符串由 DP 处理，为“a”选择覆盖整个字符串的单字母段。 重建将所有位置分配给“a”，并且前缀计数确保所有其他字母的最大匹配正确计算为零。 

像“aaaaa”这样完全统一的字符串永远不会触发任何有益的分割。 在 DP 术语中，引入更高字母的每个转换都会减少匹配，因此算法将所有字符保留在“a”段中，从而产生零替换。 

像“ababab”这样的高度交替的字符串迫使 DP 决定是否分成多个片段或折叠成更少的字母。 最佳解决方案通常会分解为少量分段，并且基于前缀的评估可确保算法正确计算每个分段的好处，而不会过度计算本地匹配。
