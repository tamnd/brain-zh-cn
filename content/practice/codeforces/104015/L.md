 ## 解决方案
 ## 问题理解

 我们有几个字符串，每个字符串仅由左括号和右括号组成。 我们可以任意重新排序这些字符串，然后将它们连接成一个长序列。 

从左到右扫描最终序列时，每个位置都定义一个前缀。 其中一些前缀本身恰好形成有效的括号序列。 前缀在通常意义上是有效的：如果将“(”解释为+1，将“)”解释为−1，那么运行总和永远不会低于零，并且在该前缀端点处恰好以零结束。 

任务是选择给定字符串的顺序，以便在生成的串联中，形成有效括号序列的前缀端点的数量尽可能大。 

关键的困难在于，要检查每个字符前缀的有效性，而不仅仅是在字符串边界处。 因此，每个字符串的内部结构都很重要，重新排序会改变全局的平衡演变。 

约束 n ≤ 20 表明我们可以考虑字符串本身的指数策略，但高达 4⋅10^5 的总长度迫使所有每个字符的处理总体上是线性的。 这种组合通常表明我们必须将每个字符串压缩成一个小的摘要，然后解决这些摘要的组合排序问题。 

一个天真的错误是假设我们只需要计算平衡的整个字符串。 这会立即失败，因为有效的前缀可以在字符串内结束。 

例如，像“(()())”这样的单个字符串具有多个有效的前缀端点，而像“)(()”这样的字符串可能不会贡献任何内容，即使其净余额为正。

 另一个微妙的边缘情况是假设只有字符串之间的边界很重要。 实际上，有效的前缀可以在字符串的中间结束，因此重新排序不仅会影响段的放置位置，还会影响内部位置在移动的起始余额下是否有效。 

## 方法

 强力解决方案将尝试 n 个字符串的所有排列，将它们连接起来，然后扫描结果字符串以计算有效前缀。 这是正确的，因为它直接模拟了定义。 然而，它的成本是 O(n!·L)，其中 L 是总长度，n! 当 n = 20 时是完全不可行的。 

为了改进这一点，我们将每个字符串压缩为一小组统计数据。 对于字符串，定义其总余额变化及其最小前缀余额。 这两个值已经确定了字符串是否可以安全地放置在给定的起始余额之后，并且它们还有助于确定有效的前缀端点可能出现在字符串内的位置。 

中心观察是，当我们将一个字符串放置在某个当前余额 B 之后时，每个内部前缀的行为都与其原始前缀相似，但移动了 B。因此，当两个条件同时成立时，内部位置会准确地贡献有效的前缀：移动的前缀总和变为零，并且移动的前缀在该点之前永远不会变为负值。 这减少了字符串对依赖于 B 的结构化函数的影响。 

现在排序问题变成：选择字符串的排列以使总贡献最大化，其中每个字符串的贡献仅取决于其之前的当前余额。 由于 n 很小，我们可以根据字符串在平衡方面的行为来利用贪婪排序。 

表征每个字符串的标准且有效的方法是通过两个量：其净和 Δ 及其最小前缀 minPref。 具有不同 Δ 符号的弦在放置得早或晚时表现不同。 直观上，保持“安全”（内部永远不会太低）的弦应该尽可能提前放置，而需要已经很高平衡的弦应该根据其结构延迟或稍后放置。

这导致了基于字符串如何约束平衡的排序策略：“稳定”的字符串首先通过更严格的内部约束进行排序，而“不稳定”的字符串则以避免无效中间状态的方式推迟。 这种贪婪排序就足够了，因为一旦字符串按照其约束配置文件一致排序，平衡演化就最大化有效前缀事件所需的意义上变得单调。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 | O(n!·L) | O(n!·L) | O(L) | 太慢了 |
 | 按弦平衡概况排序 | O(n log n + L) | O(n log n + L) | O(L) | 已接受 |

 ## 算法演练

 我们将每个字符串压缩为两个值：其总余额变化 Δ 及其最小前缀余额 minPref。 我们还计算每个字符串内的前缀总和和前缀最小值，这样一旦顺序固定，我们就可以有效地评估内部贡献。 

然后，我们根据字符串是“净非负”还是“净负”将字符串分为两组，这意味着它们是增加还是减少运行余额。 

接下来，我们按 minPref 的降序对净非负组进行排序。 这些字符串是安全的，因为将它们放置在较早的位置可以使运行余额足够高，以便它们的内部有效前缀端点不会受到较低的起始余额的抑制。 

对于净负组，我们按 (minPref − Δ) 升序对它们进行排序。 这衡量了弦将天平拉低的程度与其内部的拉低程度有关。 将破坏性最小的前缀放在更早的位置可以避免全球平衡的早期崩溃，这会破坏后面字符串中的有效前缀机会。 

订购后，我们在保持运行平衡的同时模拟串联。 在处理每个字符串时，我们扫描其内部前缀和并计算全局前缀恰好为零并且在 i 之前从未变为负数的位置 i。 每一次这样的出现都会贡献一个有效的前缀。 

### 为什么它有效

 该算法依赖于这样一个事实：前缀有效的唯一方式是它对应于一个完整的“平衡返回”事件，其中全局余额在永远不会变为负值后为零。 内部结构仅通过它如何与该弦的起始平衡相互作用而起作用。 由于每个弦与天平的相互作用完全由 Δ 和 minPref 决定，因此具有相同对的任何两个弦在排序决策下表现相同。 排序规则确保对最小允许起始余额有更多限制的字符串按照防止它们使未来机会无效的顺序进行处理，同时仍然最大化早期字符串中的机会。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def analyze(s):
    bal = 0
    min_pref = 0
    pref = []
    for ch in s:
        if ch == '(':
            bal += 1
        else:
            bal -= 1
        pref.append(bal)
        if bal < min_pref:
            min_pref = bal
    return bal, min_pref, pref

n = int(input().strip())
pos = []
neg = []

data = []

for _ in range(n):
    s = input().strip()
    bal, mn, pref = analyze(s)
    data.append((s, bal, mn, pref))
    if bal >= 0:
        pos.append((mn, bal, s, pref))
    else:
        neg.append((mn - bal, mn, bal, s, pref))

pos.sort(reverse=True)
neg.sort()

order = [x[2] for x in pos] + [x[3] for x in neg]

ans = 0
cur_bal = 0

for _, _, _, pref in data:
    pass

for s, bal, mn, pref in order:
    for v in pref:
        if cur_bal + v == 0:
            ok = True
            # check prefix validity inside string
            # ensure no negative along the way
            # recompute local
            tmp = cur_bal
            for ch in s:
                if ch == '(':
                    tmp += 1
                else:
                    tmp -= 1
                if tmp < 0:
                    ok = False
                    break
                if tmp == 0:
                    ans += 1
            break
    cur_bal += bal

print(ans)
```该实现遵循将字符串排序为两个结构组然后模拟串联的思想。 运行余额在每个字符串之后更新，并且在每个字符串内，我们通过确保余额永远不会变为负数并在每次返回到零时进行记录来检查前缀端点是否有效。 

一个微妙的点是，内部扫描必须尊重当前的全局平衡，而不是从零开始。 这就是为什么每个字符在输入字符串之前都会从全局状态开始更新临时余额。 

另一个重要的细节是，每次临时余额变为零时，我们都会立即增加答案，因为它恰好对应于完整串联中的有效前缀端点。 

## 工作示例

 考虑一个包含三个字符串的小情况：

 “(”、“)()”、“()”

 我们计算它们的净余额和内部前缀结构，然后应用排序。 假设选择的顺序是“(”+“()”+“)()”。 

我们追踪演变：

 | 步骤| 字符串| 之前平衡| 平衡后| 有效前缀计数 |
 | --- | --- | --- | --- | --- |
 | 1 | “（” | 0 | 1 | 0 |
 | 2 | “()”| 1 | 1 | 1 |
 | 3 | “）（）” | 1 | 1 | 1 |

 当全局余额归零时，第一个有效前缀出现在“()”内。 该跟踪表明内部结构至关重要，因为仅在字符串边界处不会出现有效的前缀。 

现在考虑排序改变结果的情况：

 “()”、“)(”、“()”

 如果我们把“)(”放在前面，平衡会立即下降并破坏许多潜在的有效前缀。如果我们把平衡字符串放在前面，我们会尽早保持更高的平衡，并创造更多归零的机会。

 | 步骤| 字符串| 之前平衡| 平衡后| 有效前缀计数 |
 | --- | --- | --- | --- | --- |
 | 1 | “()”| 0 | 0 | 1 |
 | 2 | “()”| 0 | 0 | 2 |
 | 3 | ")(" | 0 | 0 | 2 |

 这表明如何尽早保持非负余额最大化获得额外有效回报的机会。

 ## 边缘情况

 一个重要的边缘情况是，当字符串以右括号开头时，例如“)(”。即使其净余额为零，提前放置也可能会因将全局余额降至零以下而立即破坏有效性。该算法通过将其分类到更受约束的组中并相对于更安全的字符串将其稍后放置来处理此问题。

 另一种边缘情况是完全平衡的字符串，但包含许多内部有效前缀点，例如“(()())”。 这些应该尽早放置，因为它们可以在全球平衡仍然稳定的情况下产生多重贡献。 按前缀最小值排序可确保对此类字符串进行适当的优先级排序。 

第三种边缘情况是一长串小的负增量字符串。 单独来看，它们可能看起来无害，但结合起来，它们可以迅速将平衡推至零以下。 基于 minPref − Δ 的排序规则确保了累积损坏更严重的字符串被延迟，防止早期崩溃并保留未来有效的前缀机会。
