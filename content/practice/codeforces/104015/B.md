 ## 解决方案
 ## 问题理解

 我们有一个非常小的游戏板，只有两行，$n$列。 玩家从左上角的单元格开始，想要到达右下角的单元格。 有些单元格被陷阱挡住，踏上陷阱就会立即导致路径无效。 

移动规则比标准网格问题更加宽松。 来自任何单元格$(x, y)$，您可以移动到任何单元格$(x', y')$只要行和列最多相差一即可。 这包括水平、垂直和对角线移动，这意味着每个位置最多连接八个相邻位置（边界较少）。 任务只是确定是否存在任何有效路径$(1, 1)$到$(2, n)$永远不会踩到陷阱。 

输入尺寸非常小，$n \le 100$。 这立即表明，即使是相当幼稚的图遍历技术也足够了。 所有单元上的直接 BFS 或 DFS 最多为 200 个节点，并且每个节点具有常度边，因此即使是$O(n)$或者$O(n^2)$解决方案非常快。 

一个微妙的问题来自对角线移动规则。 由于允许对角线，因此许多仅假设 4 向或 2 行特殊结构的解决方案可能会错过有效的快捷方式。 例如，可以“跳过”陷阱，否则这些陷阱会阻塞笔直的水平路线。 

另一个极端情况是由开始和结束约束引起的。 该问题保证了$(1,1)$和$(2,n)$是安全的，所以我们永远不需要验证它们，但是盲目检查边界或错误处理索引的实现仍然可能会意外阻止它们。 

一个天真的错误是假设你只能按列向右移动。 这是错误的，因为垂直和对角线移动允许重新访问之前的列，这意味着循环存在。 任何假设列索引单调性的解决方案都是不正确的。 

## 方法

 暴力解释是将每个单元格视为一个图节点并从头开始运行搜索。 每个节点最多有八个边，具体取决于相邻单元是否在网格内而不是陷阱内。 DFS 或 BFS 探索所有可到达的单元格，直到找到目标或搜索耗尽组件。 

因为只有$2n \le 200$节点，即使重复检查所有邻居也是很便宜的。 最坏情况的工作与边的数量成正比，最多是$8 \cdot 200$，所以经过几千次操作。 

不需要更复杂的优化，但注意到为什么这个问题在结构上很简单仍然很有用。 网格很小，连接是静态的，并且不存在依赖于路径历史的权重或约束。 这使得它成为无向隐式图中的纯可达性问题。 

人们可以尝试压缩状态或贪婪地推理列转换，但这是不必要的，并且存在出错的风险，因为对角线移动会破坏简单的逐行推理。 最安全、最干净的方法是标准 BFS/DFS。

 ## 算法演练

 我们将每个单元建模为图中的一个节点。 如果允许两个节点的坐标之间移动并且两个单元都是安全的，则两个节点将连接。 

1. 将网格构建为 2 by$n$字符数组。 每个单元要么是安全的，要么是被封锁的。 
2. 维护一个相同大小的访问数组，以避免重新访问单元格并陷入对角线移动造成的循环中。 
3. 使用起始单元初始化队列（或堆栈）$(1, 1)$。 
4. 重复从数据结构中提取一个单元格并将其视为当前位置。 
5. 如果当前位置是$(2, n)$，立即返回成功，因为我们找到了有效的路径。 
6. 通过改变行来尝试最多八个相邻的移动$-1, 0, +1$并按列$-1, 0, +1$，跳过零移动。 
7. 对于每个邻居，检查它是否位于网格内并且不是陷阱。 
8. 如果邻居有效且未被访问，则将其标记为已访问并将其推入队列。 
9. 如果搜索结束没有到达$(2, n)$，返回失败。 

关键的设计选择是在推入队列时立即标记已访问。 这可以防止通过不同的对角路径重新访问相同的状态，否则会产生不必要的重复。 

### 为什么它有效

 网格形成一个未加权的图，其中每个移动都是可逆的并且具有相同的成本。 BFS 或 DFS 从一开始就精确地探索可到达的节点集。 由于每个有效路径都对应于该图中的一系列有效边，因此达到$(2, n)$搜索中就相当于游戏中存在有效路径。 被访问的结构确保终止而不考虑删除任何可达配置，因为它仅防止冗余探索，而不是可达性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input().strip())
    g = [input().strip() for _ in range(2)]
    
    # (row, col), 0-indexed
    start = (0, 0)
    target = (1, n - 1)
    
    if g[0][0] == '1' or g[1][n - 1] == '1':
        print("NO")
        return
    
    vis = [[False] * n for _ in range(2)]
    q = deque()
    q.append(start)
    vis[0][0] = True
    
    while q:
        r, c = q.popleft()
        if (r, c) == target:
            print("YES")
            return
        
        for dr in (-1, 0, 1):
            for dc in (-1, 0, 1):
                if dr == 0 and dc == 0:
                    continue
                nr, nc = r + dr, c + dc
                if 0 <= nr < 2 and 0 <= nc < n:
                    if not vis[nr][nc] and g[nr][nc] == '0':
                        vis[nr][nc] = True
                        q.append((nr, nc))
    
    print("NO")

if __name__ == "__main__":
    solve()
```该实现直接镜像了前面描述的 BFS。 网格存储为两个字符串，索引保持从零开始，以避免边界处出现差一错误。 嵌套循环结束$(-1, 0, 1)$对于行和列，干净地枚举所有 8 个可能的移动，而无需手动列出它们。 

一个常见的错误是忘记排除$(0,0)$移动，这会错误地无限期地重新插入相同的单元格。 另一个是将访问标记延迟到出队时间，这可能导致同一节点通过不同的对角线重复入队，即使约束很小，也会不必要地增加运行时间。 

## 工作示例

 考虑一个简单的网格：```
n = 4
row1 = 0000
row2 = 0010
```我们追踪 BFS 探索：

 | 步骤| 当前| 扩容后的队列 | 访问过的补充 |
 | ---| ---| ---| ---|
 | 1 | (1,1) | (1,2), (2,1), (2,2) | (1,2), (2,1), (2,2) | (1,2), (2,1), (2,2) | (1,2), (2,1), (2,2) |
 | 2 | (1,2) | ... | 如果安全的话邻居会添加|
 | 3 | ... | ... | ... |

 从一开始，搜索很快就会发现，即使陷阱阻挡了第 2 行中的直接路径，对角线移动也允许通过移动第 2 或第 3 列的行来绕过它。 

现在考虑一个阻塞示例：```
n = 3
row1 = 010
row2 = 101
```| 步骤| 当前| 扩容后的队列 | 访问过的补充 |
 | ---| ---| ---| ---|
 | 1 | (1,1) | (1,2), (2,1) | (1,2), (2,1) | (1,2), (2,1) | (1,2), (2,1) |

 这表明即使陷阱交替存在，对角线移动也可以保持连通性。 

第二条轨迹表明，BFS 自然地发现多步对角线转换，而不需要任何特殊的外壳。

 ## 边缘情况

 一种常见的边缘情况是陷阱形成之字形，似乎阻碍了直线运动，但仍然留下了对角线逃脱。 例如：```
n = 3
000
010
```从$(1,1)$, BFS 可以移动到$(2,2)$对角线，然后$(1,3)$，最后到$(2,3)$。 该算法可以正确处理这个问题，因为总是探索所有八个方向。 

另一种边缘情况是唯一有效路径重复切换相邻列的行。 如果没有对角线移动，这将需要显式的垂直转换，但在这里它作为邻居枚举的一部分自然发生。 

最后，除了薄的蜿蜒走廊之外几乎所有单元都被阻挡的情况仍然可以正确处理，因为 BFS 不假设任何方向偏差并统一处理每个可达配置。
