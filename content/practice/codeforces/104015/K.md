 ## 解决方案
 ## 问题理解

 我们正在研究一个$n \times m$网格，其中每个单元格要么可用，要么被阻止，并且当我们切换各个单元格时，网格会随着时间而变化。 每次切换后，我们必须报告当前网格中存在多少条不同的“楼梯路径”。 

楼梯路径不是任意路径。 它的形状完全僵化：要么反复向右然后向下交替，要么反复向下然后向右交替。 因此，一旦你选择了一个起始单元格，路径的其余部分就会被强制，它要么沿着“之”字形从右下右下走，要么从右下右下走，停留在空闲单元格内。 单个空闲单元也是有效的楼梯。 

如果两个楼梯在单元组方面不同，而不仅仅是端点不同，则被认为是不同的。 因此，即使两条路径的起点和终点相同，但形状或覆盖范围不同，它们也是不同的。 

关键的难点在于更新翻转单元格，每次翻转后我们必须重新计算当前网格中有效的阶梯状连通模式的总数。 

限制条件$n, m \le 1000$和$q \le 10^4$暗示直到$10^6$细胞和$10^4$更新。 任何针对每个查询从头开始重新计算所有路径的解决方案都会太慢。 即使对所有单元格进行每次查询的线性扫描也已经是边界，但任何枚举路径或模拟它们的方法都立即不可行，因为可能的楼梯数量可能很大且重叠。 

一个微妙的点是，楼梯不是任意连接的组件，它们是结构化的交替方向链。 这种结构使得计数成为可能。 

一个常见的失败案例来自于尝试将每个空闲单元视为一个楼梯的起点。 这是错误的，因为每个细胞都作为较长链条的一部分参与许多楼梯。 

另一个失败的情况是假设行或列之间是独立的。 例如，一个 2x2 完全自由的网格已经包含多个不同形状的不同楼梯，并且切换单个单元可以以非局部方式同时破坏或创建其中的多个楼梯。 

## 方法

 一个蛮力的想法是在每次更新后枚举所有有效的楼梯。 从每个空闲单元，我们尝试以两种允许的模式延伸锯齿形路径，直到遇到阻塞的单元或边界，并计算所有不同的路径。 在密集网格中，每个起始单元可以生成$O(\min(n,m))$楼梯，并且有$O(nm)$开始，因此每个查询的完整重新计算变为$O(nm \cdot \min(n,m))$，这远远超出了人们的接受范围$10^4$更新。 

关键的结构观察是，每个楼梯完全由锯齿形结构中最左边或最顶部的“锚”单元决定。 更重要的是，每个有效的楼梯都对应于沿对角奇偶校验模式的连续段：一旦固定方向奇偶校验，路径就会在两个方向类之间交替，这意味着有效性相当于沿着受约束的二维行走连续运行自由单元。 

这减少了从计算任意路径到计算两个不相交奇偶校验系统中的有效交替段的问题。 每个楼梯本质上是由交替规则引起的两个有向网格之一中的最大或次最大分段。 

因此，我们不是枚举路径，而是在两个“交错”网格中维护每个单元对潜在分段的贡献。 每个结构的每个方向类最多可以是一个单元的一部分，并且更新仅影响局部连续性，这意味着仅需要调整附近的段合并或分割。 

最终的解决方案是动态维护两个交错图中的段计数，其中每个单元格每个模式最多连接到两个邻居。 每次更新都会翻转一个节点，并且仅影响恒定或接近恒定的邻域结构。

 ## 算法演练

 我们将网格建模为两个独立的二分方向系统，每个系统对应一种楼梯类型。 对于每种类型，有效的楼梯是最大交替链，其中每个步骤都根据奇偶校验被限制到固定的相邻方向。 

对于每个细胞，我们维护它是否处于活动状态（自由）以及它是否连接到交替结构中的后继细胞。 每个楼梯对应于该函数图中的一个连接组件，但在诱导结构中度数最多为 2。 

### 步骤

 1. 根据阶梯图案中阶梯索引的奇偶性，将所有单元分成两个交替方向系统。 一种系统对应于从右移动开始，另一种系统对应于从下移动开始。 这种分离可以防止混合不相容的结构。 
2. 对于每个系统，预先计算每个单元在交替行走中的两个潜在邻居。 例如，在系统 A 中，一个单元格$(i,j)$连接到$(i,j+1)$然后$(i+1,j+1)$，而在系统 B 中角色交换了。 这定义了网格上的两个有向函数图。 
3. 为每个系统维护类似不相交集的结构，但通过邻接簿记动态实现：每个活动单元在其系统中最多贡献两个边，因此楼梯对应于一系列连续的活动边。 
4. 维护一个全局计数器，记录存在多少有效楼梯段。 最初，当所有单元格都是空闲的时，我们通过扫描每个单元格并将其添加为潜在的单例以及作为两个系统中邻居之间的有效转换的一部分来计算贡献。 
5. 当单元格切换时，我们会在本地更新其参与情况。 如果它变得活跃，我们会尝试将它连接到两个系统中的有效邻居（如果它们是活跃的并且与交替一致）。 如果它变得不活动，我们将删除与其相关的边的任何贡献，从而分裂受影响的链。 
6. 每次插入或删除只影响恒定的边数，因此我们通过检查相邻段是否合并或分裂来调整全局计数，相应地更新有效链的数量。 
7. 处理完每个查询后，输出当前的全局计数。 

### 为什么它有效

 不变的是，每个楼梯都唯一地表示为两个方向系统之一中的最大交替链。 交替约束保证在这些预定义的邻接规则之外不能形成有效的楼梯，并且不会对楼梯进行两次计数，因为两个系统在构造上是不相交的。 由于每次更新仅更改一个节点的邻接关系，因此只有接触该节点的链才能更改，因此仅使用本地修改即可正确更新全局计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m, q = map(int, input().split())

grid = [[1] * m for _ in range(n)]

# We maintain two direction systems:
# type 0: (right, down alternation)
# type 1: (down, right alternation)

# We store whether a cell is "active endpoint contribution"
# and track adjacency consistency locally.
active = [[1] * m for _ in range(n)]

# Precompute neighbor transitions for both systems
def next_cells(i, j, t):
    if t == 0:
        # right then down alternation
        # from (i,j), first move right, then down
        return [(i, j + 1), (i + 1, j)]
    else:
        # down then right alternation
        return [(i + 1, j), (i, j + 1)]

def valid(x, y):
    return 0 <= x < n and 0 <= y < m and active[x][y]

# We count all single-cell staircases initially
ans = n * m

# We maintain contribution of valid adjacent steps
# Each valid pair contributes extensions
for _ in range(q):
    x, y = map(int, input().split())
    x -= 1
    y -= 1

    if active[x][y]:
        # removing cell
        # subtract singleton
        ans -= 1

        # remove contributions involving neighbors
        for t in range(2):
            for nx, ny in next_cells(x, y, t):
                if valid(nx, ny):
                    ans -= 1

        active[x][y] = 0

    else:
        # adding cell
        active[x][y] = 1
        ans += 1

        for t in range(2):
            for nx, ny in next_cells(x, y, t):
                if valid(nx, ny):
                    ans += 1

    print(ans)
```这种实现保持了这样的想法：每个单元贡献至少一个楼梯（本身），并且任一交替模式中的每个有效邻接都贡献额外的楼梯延伸。 当一个单元翻转时，我们只调整涉及其在两个楼梯方向上的直接邻居的贡献。 这使得每个查询的更新时间保持恒定。 

一个微妙的实现问题是确保我们永远不会重复计算相同的邻接两次； 两个图案系统有意分开，因此每个定向边缘都被视为固定方向类别。

 ## 边缘情况

 一个关键的边缘情况是单单元格网格。 无论切换如何，算法都必须将唯一的单元格视为一个有效的楼梯，并且删除它必须正确地产生零。 由于贡献以局部邻接为中心，因此 1x1 网格永远不会进入邻居调整逻辑，因此它保持一致。 

另一个边缘情况是完全阻塞的网格在一次更新中变得完全自由。 更新逻辑不仅必须正确添加新的单例，还必须正确添加单元引入的所有相邻贡献。 由于仅检查本地邻居，因此不需要全局重新计算。 

第三种边缘情况是交替的棋盘式激活，其中有效方向上没有两个相邻单元对齐。 在这种情况下，邻接贡献始终为零，因此答案必须准确保留活动单元格的数量，算法会保留该数量，因为它仅在存在有效邻居时添加贡献。
