 ## 解决方案
 ## 问题理解

 我们正在处理一个边长未知的矩形，比如说$a$和$b$，都是严格的正实数。 我们没有直接得到矩形。 相反，我们被告知有关其侧面的两条汇总信息。 

一篇文章说，如果我们恰好选取矩形的两条不同的边，它们的总长度是$x$。 因为长方形有两条边长$a$和长度的两侧$b$，这个条件意味着我们选择$a+a$， 或者$b+b$， 或者$a+b$，取决于选择哪一边。 

第二部分说，如果我们恰好选择三个不同的边，它们的总长度是$y$。 这意味着我们正在总结$2a+b$或者$a+2b$，同样取决于排除哪一侧。 

所以结构是：我们必须赋值$a, b > 0$使得双方存在一致的选择，总和为$x$，并且三边的一致选择总和为$y$。 在所有这些有效的矩形中，我们想要最小可能的周长$P = 2(a+b)$。 如果不存在积极的解决方案，我们必须报告失败。 

约束条件允许$x, y \le 10^9$，因此任何解决方案都必须将问题简化为恒定时间代数情况。 对可能的辅助任务进行暴力破解或连续搜索$a, b$是不可能的。 

主要的微妙之处在于“两侧”和“三边”约束不是固定的表达方式。 它们取决于选择哪一方，因此存在多种结构情况，其中一些以不明显的方式重叠。 

一个天真的错误是假设$x = a+b$和$y = 2a+b$，给出一个单一的线性系统。 这错过了像这样的情况$x = 2a$或者$x = 2b$，这都是同样有效的解释。 另一种失败模式是忽略两个约束必须满足相同的分配$a, b$，不独立。 

## 方法

 关键的困难在于“两侧之和”和“三侧之和”的陈述并不能唯一地标识包括哪些侧面。 矩形只有两个不同的边长，因此约束的每个有效解释都减少为选择多少次$a$和$b$出现在每个总和中。 

对于两边和$x$，可能性是有限的。 我们要么选择长度的两边$a$, 给予$2a = x$，或长度两侧$b$, 给予$2b = x$，或每个的一侧，给出$a+b = x$。 

对于三边之和$y$，我们排除一侧。 排除一个$a$给出$a + 2b = y$。 排除一个$b$给出$2a + b = y$。 

因此，整个问题简化为检查一小组恒定大小的线性系统，这些系统是通过组合三种情况之一而形成的$x$两种情况之一$y$。 每个组合最多给出两个线性方程$a, b$。 我们解决它们，检查积极性，并计算周长。 

蛮力解释会尝试不断变化$a, b$或猜测作业，这是不必要的。 该结构是离散的：仅存在五种有效形式。 

优化源于认识到对称性将搜索空间减少到恒定的可能性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（连续或天真的猜测）|$O(\infty)$/ 不可行 |$O(1)$| 太慢了 |
 | 有效侧面作业的案例枚举 |$O(1)$|$O(1)$| 已接受 |

 ## 算法演练

 我们系统地测试了这两个方程的所有一致解释。 

1. 枚举两侧和的所有有效解释$x$:

 我们考虑$2a = x$,$2b = x$， 和$a + b = x$。 

每个都代表了选择矩形中两条边的不同方式。 
2. 枚举三边和的所有有效解释$y$:

 我们考虑$2a + b = y$和$a + 2b = y$。 

这些对应于排除任一类型的一侧。 
3. 对于每对解释，形成一个线性系统$a$和$b$。 

明确解决。 例如，如果$2a = x$和$2a + b = y$， 然后$a = x/2$和$b = y - x$。 

该结构确保每个系统都有直接替代解决方案。 
4. 检查有效性条件。 

两个都$a > 0$和$b > 0$必须持有。 如果任一结果为非正值，则丢弃该解决方案。 这反映了矩形边不能退化的几何要求。 
5. 计算周长$P = 2(a + b)$。 

跟踪所有有效解决方案的最小值。 
6. 如果不存在有效配置，则输出$-1$。 

### 为什么它有效

 每个有效矩形恰好对应于边如何贡献两个和的有限组合分配之一。 由于每个金额仅取决于有多少$a$和$b$除了这些情况之外，没有隐藏的自由度。 穷尽所有可能性确保完整性，并且每个候选都在其定义的约束下进行精确检查，确保正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())
    INF = float('inf')
    ans = INF

    def upd(a, b):
        nonlocal ans
        if a > 0 and b > 0:
            ans = min(ans, 2 * (a + b))

    # Case 1: x = 2a
    a = x / 2
    # y = 2a + b
    b = y - 2 * a
    upd(a, b)

    # Case 2: x = 2b
    b = x / 2
    a = y - 2 * b
    upd(a, b)

    # Case 3: x = a + b
    # y = 2a + b => b = y - 2a => a + (y - 2a) = x => y - a = x => a = y - x
    a = y - x
    b = x - a
    upd(a, b)

    print(-1 if ans == INF else f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```该实现直接反映了两侧和的三种结构解释，并针对兼容的三侧约束来求解每个结构解释。 辅助函数`upd`过滤边长变为非正值的无效几何解。 浮点运算就足够了，因为公式只涉及加法、减法和除以二，并且所需的精度为$10^{-4}$。 

一个微妙的点是，每种情况都隐含地假设使用的边之间具有一致的配对。$x$以及哪一边被排除在外$y$。 混合不兼容的解释是不可能的，因为每种情况都已经编码了完整的结构配置。

 ## 边缘情况

 当天真的解算器假设$x = a + b$作为唯一的可能性。 用于输入$x = 6, y = 4$，这导致$a = y - x = -2$，立即违反积极性。 该算法在执行过程中正确地拒绝了它`upd`查看。 

另一种边缘情况是多种配置产生相同的矩形。 为了$x = 10, y = 15$，所有情况都崩溃为$a = b = 5$。 该算法不会尝试对这些情况进行重复数据删除，因为它只跟踪最小周长，因此重复的候选者不会影响正确性。 

第三种情况是浮点除法出现在$a = x/2$。 由于所有计算都是线性的并且仅涉及除以二，因此在所需的情况下精度损失可以忽略不计$10^{-4}$宽容，不需要特殊的理性处理。
