 ## 解决方案
 ## 问题理解

 给定两个长度相等的字符串，并且允许我们执行一次交换操作。 交换以特定方式受到限制：我们在第一个字符串中选择一个位置，在第二个字符串中选择一个位置，然后交换这两个字符。 完成一次交换后，我们希望两个字符串变得相同。 

这不是一般的重排问题。 我们不允许在字符串内进行交换，也不允许进行多个操作。 我们只得到一次跨字符串交换，即使字符串最初已经匹配，我们也必须使用它。 

该操作的关键结构结果是总共只有两个位置发生变化，每个字符串一个。 所有其他位置永远保持固定。 

输入大小最多允许 10 个测试用例，每个测试用例的字符串长度最多为 10,000。 每次测试的线性扫描是很容易实现的，但是任何与字符串位置平方的东西仍然是安全的。 然而，在最坏的情况下，尝试所有交换对将涉及每次测试多达 1 亿次操作，这在 Python 中的多个测试中是边缘或不安全的。 

一个微妙的边缘情况是字符串已经相等。 即使如此，我们仍然必须执行交换。 如果我们在任何位置交换相同的字符，字符串将保持相等，但这仅在此类交换不会在其他地方引入不匹配的情况下才有效。 

当不匹配模式很小但与任何单个交换“不兼容”时，就会出现另一个棘手的情况。 例如，如果纠正一个不匹配可以修复一个位置，但必然会破坏另一个不相关的位置，则转换变得不可能。 

## 方法

 暴力解决方案尝试每对索引$(i, j)$, 掉期$s_i$和$t_j$，并检查结果字符串是否匹配。 每张支票费用$O(n)$，并且有$O(n^2)$交换、给予$O(n^3)$每个测试用例。 和$n = 10^4$，这远远超出了可行的限度。 

我们可以通过观察交换后的平等实际上意味着什么来大大减少这种情况。 

假设我们交换$s_i$和$t_j$。 交换后位置$i$在$s$变成$t_j$，和位置$j$在$t$变成$s_i$。 对于所有其他职位$k \neq i, j$，我们必须已经有$s_k = t_k$，因为这些位置未受影响。 

因此，整个问题归结为理解不匹配。 让我们定义所有索引，其中$s_k \neq t_k$。 称这些为不匹配位置。 如果存在超过 2 个不匹配的情况，则一次交叉交换无法解决所有问题，因为一次交换仅直接影响两个位置，而不会间接影响其他位置。 

如果恰好有 0 个不匹配，则字符串已经相等。 由于我们仍然必须执行交换，因此我们需要确保交换两个位置不会破坏相等性。 只有当我们在一对索引处交换两个字符串中的相同字符时，这才是可能的，只有当两个字符串中的不同位置至少存在一个字符时，这种情况才可能发生，这样交换就可以保持相等性。 在这个问题的约束下，这减少了检查字符串中相应位置是否存在具有相同字符的索引对，这总是正确的，除非所有字符都以严格的方式相同，而交换后会中断。 

如果索引恰好有 2 个不匹配$i$和$j$，那么我们只有交换才能修复它们$s_i$和$t_j$使两个位置同时匹配。 这需要精确的交叉对齐条件：$s_i = t_j$和$s_j = t_i$。 

这给出了一个干净的 O(n) 解决方案。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 同时扫描两个字符串并记录它们不同的所有索引。 这些是唯一重要的位置，因为未更改的位置必须已经是正确的。 
2. 如果不匹配的数量大于2，则立即返回“否”。 一次交换无法修复两个以上的头寸，并且交换索引之外的不匹配无法修复。 
3. 如果不匹配的数量恰好为 0，我们无论如何都必须执行交换。 我们检查是否存在任何交换不会破坏相等性的索引对。 当字符串在各个位置上至少包含一对重复字符时，这种情况始终是可能的； 然而，在这个问题结构中，我们可以安全地回答“是”，因为我们总是可以选择任何 i = j 交换，这使字符串保持不变。 
4. 如果不匹配的个数恰好为 2，则令不匹配的索引为$i$和$j$。 我们检查是否交换$s_i$和$t_j$使两个位置匹配，意思是$s_i = t_j$和$s_j = t_i$。 如果是，则输出“Yes”，否则输出“No”。 
5. 如果不匹配的数量恰好为 1，则不可能通过一次交叉交换来修复单个不匹配而不破坏另一个位置，因此输出“No”。 

### 为什么它有效

 不变量是所有未选择用于掉期的指数保持不变。 因此，每个非交换的不匹配必须在操作之前得到解决，这迫使不匹配集的大小最多为 2。当恰好存在两个不匹配时，交换必须以交叉一致的方式将它们配对，否则在操作后至少保留一个不匹配。 当不匹配为零时，有效性仅取决于自交换保持相等性、满足“恰好一个操作”约束而不改变正确性这一事实。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input())
    for _ in range(k):
        n = int(input())
        s = input().strip()
        t = input().strip()

        diff = []
        for i in range(n):
            if s[i] != t[i]:
                diff.append(i)

        d = len(diff)

        if d == 0:
            # must still perform one swap; i = j works
            print("Yes")
        elif d == 2:
            i, j = diff
            if s[i] == t[j] and s[j] == t[i]:
                print("Yes")
            else:
                print("No")
        else:
            print("No")

if __name__ == "__main__":
    solve()
```该实现完全侧重于不匹配跟踪。 扫描在线性时间内构建不匹配列表。 决策逻辑直接反映了结构约束：在单次交叉交换下只能修复 0 或 2 个不匹配。 

“恰好一次交换”的要求在$d = 0$通过允许简单的自交换来解决这种情况，这可以保留两个字符串而不违反操作约束。

 ## 边缘情况

 当字符串已经相等时，不匹配列表为空。 该算法将此视为有效的“是”情况，因为自交换不会更改任何一个字符串。 这可以避免在操作仍然强制的情况下错误地拒绝有效配置。 

当恰好存在一个不匹配时，不匹配索引将单独出现在差异列表中。 该算法立即拒绝它，因为没有任何交换可以同时修复和保留所有其他位置，并且没有其他不匹配与其配对。 

当恰好存在两个不匹配时，算法会显式检查交叉相等性。 这确保了交换不仅移动字符，而且同时对齐两个位置，这对于操作后完全相等是必要的。
