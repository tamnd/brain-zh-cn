 ## 解决方案
 ## 问题理解

 我们拥有一排船只，每艘船只都有一定的耐用性，并且有固定的攻击模式，该模式始终针对当前最左边的幸存船只，然后是当前最右边的幸存船只，并重复这种交替，直到总共$k$已发生攻击或所有船只均沉没。 

每次攻击都会使所选船只的耐久度降低一倍。 当一艘船达到零时，它会从线上消失，其余的船会缩小差距，因此新的“第一艘”和“最后一艘”总是在剩余的活动段上定义。 任务是确定在执行所有攻击后有多少艘船完全沉没。 

重要的困难来自于约束大小。 最多可以有$10^4$测试用例，所有测试的船舶总数最多为$2 \cdot 10^5$，但是攻击次数$k$可以大到$10^{15}$。 这立即排除了每次攻击执行一个操作的任何模拟。 即使每次攻击都进行线性扫描也是不可能的，因为$k$可以矮化$n$提高了许多数量级。 

简单的模拟也会因两端的重复删除而陷入困境。 如果用列表来实现并弹出或移动，则存在风险$O(n)$每次删除，在最坏的情况下速度太慢。 

当一侧排空速度比预期快时，就会出现微妙的故障模式。 例如，如果所有小值都集中在一侧，则即使一端耗尽，除非明确处理，否则一种简单的交替方法可能会错误地继续“切换”。 

## 方法

 直接蛮力方法很简单：维护两个指针$l$和$r$，模拟每次攻击，减少所选端点，并在船舶达到零时向内移动指针。 这是正确的，因为它确实反映了该过程。 然而，每次攻击都是$O(1)$，但最多有$10^{15}$攻击，因此不可能在时限内执行。 

关键的观察是我们实际上不需要单独模拟每个攻击。 重要的是每个端点在其中一个端点耗尽之前消耗了多少次攻击。 在任何时刻，左边或右边的下一艘船都会被重复攻击，直到变成零或直到对方占据主导地位。 

我们没有考虑交替操作，而是将过程压缩为块。 在比较可用的攻击预算时，我们总是尝试完全耗尽两个端点中较小的一个。 如果双方都活着，我们会比较他们当前的耐久度并批量分配攻击：要么先摧毁左边的船，要么先摧毁右边的船。 这将这个过程变成了从两端进行删除的序列，每个删除都在恒定的时间内完成。 

一旦船舶被移除，我们将继续使用更新的端点和剩余的端点$k$。 每艘船最多被移除一次，因此所有测试用例的总工作量是线性的。 

| 方法| 时间复杂度| 空间复杂度| 判决|
 | --- | --- | --- | --- |
 | 暴力模拟|$O(k)$|$O(1)$| 太慢了|
 | 两指针贪婪压缩|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们维护两个指针，一个位于活动段的左端，一个位于右端，以及一个计数器，用于显示沉没的船只数量。 

1.初始化两个索引$l = 0$,$r = n - 1$，沉船计数器为零。 我们还跟踪当前左右舰艇的剩余耐久度。 
2. 虽然$l \le r$我们还有剩余的攻击$k > 0$，我们根据之间较小的耐久度来决定哪一方将首先受到攻击$a[l]$和$a[r]$。 这是因为耐久度较小的一侧在交变压力下会更早耗尽。 
3.如果$a[l] \le a[r]$，我们假设在当前平衡下，左边的船将首先被完全摧毁。 我们比较是否有足够的剩余攻击$k$充分减少$a[l]$。 如果没有，我们立即停止，因为超过此点就不能再击沉任何船只。 
4. 否则，我们减去$a[l]$从$k$，增加沉没计数器，然后移动$l$右一步。 然后我们通过以下方式降低正确船舶的耐用性：$a[l]$，因为在击杀左船的过程中，右船也有一半的时间受到攻击。 这种重新分布反映了交替的攻击模式。 
5. 对称情况适用于$a[r] < a[l]$：我们首先完全消耗掉右边的船，减去$a[r]$从$k$，增加计数器，移动$r$向左，并减少$a[l]$因此。 
6. 如果在任何时候一艘船的耐久度下降到零，则通过移动指针将其隐式删除，然后我们继续下一对。 

核心思想是每次操作至少消除一艘船，因此循环只能运行$O(n)$次。 

### 为什么它有效

 该算法保留了一个关键的不变量：每一步之后，剩余的值$k$准确地表示仍需要应用于减少的段的攻击数量，并且两个端点都反映了来自对方的所有先前交叉攻击。 

由于每次迭代都完全解析至少一个端点（两个端点中较小的一个），因此不会以违反交替结构的方式部分重新访问船舶。 该过程相当于将交替攻击分组为最大分段，其中一个端点保证首先死亡。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        l, r = 0, n - 1
        ans = 0

        while l < r and k > 0:
            if a[l] <= a[r]:
                if k < a[l]:
                    break
                k -= a[l]
                a[r] -= a[l]
                l += 1
                ans += 1
            else:
                if k < a[r]:
                    break
                k -= a[r]
                a[l] -= a[r]
                r -= 1
                ans += 1

        if l == r and k > 0:
            ans += 1 if k >= a[l] else 0

        print(ans)

if __name__ == "__main__":
    solve()
```该实现使用两个指针来表示船舶的活动部分。 每次循环迭代都会从左侧或右侧移除一艘船，具体取决于哪艘船的剩余耐久度较小。 减法步骤模拟了这样一个事实：虽然将攻击集中在一端，但另一端仍然会受到交替伤害。 

最终检查处理只剩下一艘船的情况。 如果剩余攻击足够，则算沉没。 

一个微妙的点是我们从来没有明确地模拟交替转弯。 相反，两端之间的持久性转移隐含地捕捉到了这样一个事实：随着时间的推移，两端都以交错的方式受到攻击。

 ## 边缘情况

 当只剩下一艘船时，算法从交替行为切换到单个线性消耗检查。 例如，如果$a = [7]$和$k = 5$，剩余攻击不足，因此没有额外击沉船只。 

当一侧较小时，例如$a = [1, 100, 100]$，左侧船只立即被移除，但其移除仅将少量伤害转移到右侧。 该算法正确地继续使用更新的值，而不是错误地假设对称耗尽。 

什么时候$k$在操作过程中耗尽，循环在执行任何无效减法之前中断，确保不会引入负耐久性并且不会计算额外的船只。
