 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串和一个翻转固定长度块的操作$k$，将每个 0 变为 1，将每个 1 变为 0。我们可以根据需要多次应用此操作，但所选择的长度$k$整个过程都是固定的。 目标是确定最大的此类$k$可以将整个字符串转换为全部字符串。 

这是一个关于受限翻转操作下二进制数组配置的可达性问题。 每个操作都会准确影响$k$连续持仓，这意味着效果是高度结构化的：每个持仓都参与翻转的滑动窗口，每个指数的最终值由其被覆盖次数的奇偶性决定。 

约束允许最多$n = 5000$每个测试用例和总计$\sum n^2 \le 2.5 \cdot 10^7$。 这强烈表明$O(n^2)$每个测试用例的解决方案或接近的解决方案，因为每个测试用例的任何立方都会太慢，但二次方法是可以接受的。 

一个关键的微妙之处在于，操作是可逆的，并且顺序在破坏性意义上并不重要，但它们确实通过奇偶校验进行交互。 这通常会导致贪婪或前缀奇偶推理而不是模拟。 

一个常见的陷阱是假设很小$k$总是有效，或者可行性仅取决于局部模式，例如零游程。 另一个错误是对待每一个$k$独立地进行，而没有注意到可以在线性时间内贪婪地测试可行性。 

一个简单的误导性示例是当字符串交替时，例如`1010`。 对于一些$k$，从左到右的贪婪翻转是可行的，但对于其他人来说，即使局部直觉可能表明可行性，它也会失败。 

## 方法

 一个蛮力的想法是尝试每一个候选人$k$从 1 到$n$。 对于每个$k$，我们模拟是否可以使用贪婪翻转将字符串转换为全部。 

修复一个$k$，我们从左到右处理字符串。 在每个位置$i$，我们决定是否需要翻转从$i$使当前字符变为1。跟踪之前的翻转是否影响位置$i$，我们维护一个差异数组或活动翻转的运行奇偶校验。 每次翻转都会影响一个大小的窗口$k$，因此我们在移动时添加和删除奇偶贡献。 

This simulation is$O(n)$每$k$, 给予$O(n^2)$每个测试用例。 自总计$\sum n^2$是有界的，这已经是可行的，但是我们仍然需要保证贪心策略的正确性，避免低效地从头开始重新计算。 

关键的见解是对于固定的$k$，贪婪的从左到右的策略是最优的：每当我们在考虑翻转后遇到 0 时，如果可能的话，我们就被迫在该位置翻转，因为延迟对未来的位置没有帮助，只会增加约束。 这将可行性检查简化为确定性过程。 

因此，解决方案变为：对于每个$k$，在线性时间内测试可行性，并取最大有效值$k$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每 k 的强力模拟 |$O(n^2)$每次测试|$O(n)$| 在最坏的情况下太慢（但在全局约束下可以接受）|
 | 每个 k 的最优贪心检查 |$O(n^2)$每次测试总计 |$O(n)$| 已接受 |

 ## 算法演练

 我们想要测试给定的$k$。 这个想法是模拟使用最少的必要翻转迫使每个位置变为 1 的过程。 

1.我们维护一个数组`diff`跟踪有多少活动翻转影响每个位置，但我们维护运行奇偶校验而不是完整数组`cur`。 

这是有效的，因为我们只关心影响位置的有效翻转数量是偶数还是奇数。 
2. 我们从左到右迭代字符串。 

在位置$i$，我们首先更新`cur`通过添加从以下位置开始的翻转效果$i-k$到这里就结束了，使用延迟移除结构。 
3. 我们计算当前有效值`s[i]`翻转后：

 如果`cur % 2 == 1`，该位取反； 否则它保持不变。 
4. 如果当前有效值为0，我们被迫在以下位置开始翻转$i$，因为这是固定位置的唯一方法$i$不会再次影响之前的位置。 

我们标记一个翻转开始于$i$， 增加`cur`，并将其删除安排在 (i+k`.
 5. 我们继续这个过程直到最后。 如果在任何时候我们需要翻转超出边界（即$i+k > n$），这样的配置是不可能的$k$。 

完成后，如果在这个强制过程下所有位置都为1，那么$k$是可行的。 

外循环尝试所有$k$从 1 到$n$，保留最大可行值。 

### 为什么它有效

 不变量是当我们到达位置时$i$，所有影响位置的决策严格小于$i$已经固定并且无法更改。 任何翻转开始于$i$是唯一剩余的可以影响位置的自由度$i$无需重新审视之前的指数。 因此，如果当前值为$i$为 0，不翻转$i$如果不破坏早期的正确性，以后就永远无法得到补偿。 这迫使每个位置都有一个独特的贪婪选择，使每个位置的可行性具有确定性$k$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def check(s, n, k):
    diff = [0] * (n + 2)
    cur = 0

    for i in range(n):
        cur ^= diff[i]

        if cur == 0:
            bit = s[i]
        else:
            bit = 1 - s[i]

        if bit == 0:
            if i + k > n:
                return False
            cur ^= 1
            diff[i + k] ^= 1

    return True

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        arr = [1 if c == '1' else 0 for c in s]

        ans = 1
        for k in range(1, n + 1):
            if check(arr, n, k):
                ans = k
        print(ans)

if __name__ == "__main__":
    solve()
```解决方案的核心是`check`函数，它使用基于奇偶校验的差异数组模拟固定窗口大小。 这`cur`变量表示当前位置是否翻转奇数次。 这`diff`数组存储翻转效果结束的位置，以便我们可以切换`cur`当窗口滑过边界时有效。 

外循环尝试所有可能的值$k$，更新最佳有效答案。 由于每次检查都是线性的，因此总工作量保持在约束范围内。 

一个微妙的点是我们提前将字符转换为整数。 这避免了重复的字符比较，并使翻转逻辑保持纯粹的算术，从而减少了 Python 的开销。

 ## 边缘情况

 一个关键的边缘情况是字符串以零开头并且$k$很大。 例如，`00000`和$k=5$。 该算法立即在索引 0 处翻转，因为第一个位置必须固定。 这会产生覆盖整个字符串的完整翻转，之后所有位置都变为 1。 贪心规则正确地处理了边界条件，因为它只允许翻转$i+k \le n$，确保不会尝试无效操作。 

另一种边缘情况是翻转严重重叠时，例如`101010`与小$k$。 奇偶校验机制确保重叠贡献正确取消，并且贪婪决策保持一致，因为每个位置按从左到右的顺序精确解决一次。 

最后一个微妙的情况是所需的翻转超出了数组边界。 在这样的情况下`001`和$k=2$，在位置 2 处，算法仍可能遇到零，但无法启动有效的翻转。 该函数立即拒绝此操作$k$，这是至关重要的，因为一旦窗口大小限制阻止进一步的操作，任何“稍后修复”的尝试都是不可能的。
