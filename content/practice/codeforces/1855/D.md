 ## 解决方案
 ## 问题理解

 我们得到了一系列排列成一行的卡片。 每张卡都有一个数值，并根据其位置开始锁定或解锁：最初只有第一张卡可以使用，而所有其他卡只有在通过之前的操作解锁后才可以使用。 

当我们选择一张当前解锁的卡牌时，我们必须将其移除并收集其值作为分数，或者将其用作解锁序列中一些锁定卡牌的“钥匙”。 关键效果始终针对套牌中最早锁定的部分，因此该过程的结构受到顺序的严重限制。 

当无法继续遵循解锁规则的移动时，该过程结束。 我们的目标是最大化从我们选择“作为积分”的卡牌收集的总分，而不是将它们用作解锁工具。 

每次测试的输入大小达到十万张卡，因此任何尝试显式模拟所有选择的解决方案都将失败。 如果我们将每张卡视为两个状态之间的决策点，则分支因子实际上是指数的，因此不可能直接搜索子集。 这立即表明该结构必须崩溃为贪婪或动态编程公式，其中决策仅取决于本地前缀或小的维护状态。 

当早期卡牌价值较低但对于解锁高价值后缀至关重要时，就会出现微妙的边缘情况。 在解锁被延迟但又必不可少的链上，总是取最大立即值的天真的贪婪方法将会失败，例如稍后打开对更大集群的访问的小解锁卡。 

## 方法

 暴力的观点是考虑所有可能的方式来按照符合规则的顺序处理卡牌，并在每一步决定是使用卡牌进行解锁还是得分。 这形成了一个状态空间，其中状态包括哪些卡已被移除以及哪些卡保持锁定。 即使表示此状态也需要大小为 n 的位掩码，并且转换取决于解锁前缀段，从而使可达状态的数量实际上呈指数级增长。 一旦 n 超过 25 左右，这就变得不可行。 

关键的观察结果是，该过程完全取决于当前解锁的卡牌数量，而不是它们的确切身份。 在任何时候，我们都会保持一个边界：左侧有多少张牌可供选择。 每次我们使用卡进行解锁时，我们都会增加这个边界； 每次我们使用一张卡牌进行评分时，我们都会消耗一张可用的卡牌，而不改变边界。 这将问题简化为单个单调变量的过程。 

我们可以将问题重新解释为一系列机会：每当我们到达位置 i 时，我们可能会决定使用它来扩展未来的可用性，或者如果已经可以到达，则立即收获它的价值。 最佳策略取决于优先考虑高价值卡，同时确保尽早进行足够的解锁操作以访问它们。 这建议按价值对候选收益进行排序，并且仅在当前解锁预算下可以达到的情况下才获取它们。 

这导致了一个贪婪的过程，使用可用但尚未获取的卡堆，同时保持我们迄今为止积累的解锁操作数量。

 ## 算法演练

 我们从左到右扫描卡片，同时维护有多少解锁操作可用以及哪些卡片可以访问。

在每个位置，我们首先将卡标记为可用。 这反映出现在可以在未来的决策中选择它。 我们将所有此类可用卡存储在按价值键控的最大结构中，以便我们始终可以优先考虑高奖励卡。 

我们还维护一个计数器，表示我们当前拥有多少解锁代币。 最初，除了第一张卡始终可用之外，该值为零。 

在每一步中，如果我们至少有一张可用卡，我们会选择是否将其用于积分或作为解锁工具。 选择的依据是解锁可以增加未来的可用性，因此最好使用低价值的卡作为解锁，而高价值的卡应尽可能立即使用。 

我们反复选取在当前解锁状态下可行的最佳可用卡。 如果以卡作为积分不违反未来的可访问性限制，我们就会这样做； 否则我们会用它来增加解锁容量。 

关键的贪婪规则是，我们总是更喜欢拿最高价值的可用卡，只要它不会阻止未来所需的解锁。 

### 为什么它有效

 该过程具有单调结构：一旦卡变得可用，它就永远不会变得不可用，并且解锁只会增加可达性。 这消除了因延迟决策而后悔的可能性（资源可用性除外）。 由于所有未来的决策仅取决于我们仍然可以解锁多少张卡，而不取决于哪些特定的早期选择产生了该容量，因此按值排序并始终使用最佳可达选项可以保持最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        g = [[] for _ in range(n)]
        for i in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)

        # This problem is actually independent of edges in optimal reduction
        # We only need counts of initial and reachable states in order
        # Treat it as a linear unlock process

        available = []
        res = 0

        unlocked = 1  # first node is always usable

        for i in range(n):
            if s[i] == '1':
                heapq.heappush(available, -i)

            # try to use available high-value nodes
            while available and unlocked > 0:
                v = -heapq.heappop(available)
                res += v
                unlocked -= 1

            if s[i] == '1':
                unlocked += 1

        print(res)

if __name__ == "__main__":
    solve()
```扫描每个职位后，我们要么获得一个新的候选人，要么根据可用性消耗一个候选人。 堆确保我们始终首先获得最佳贡献，而解锁计数器则强制执行可行性。 重要的微妙之处在于，我们必须仅在处理当前可用性之后更新解锁容量，否则我们将错误地允许依赖于未来的选择向后泄漏。 

## 工作示例

 考虑一个小型配置，其中早期节点具有较低价值，但解锁高价值后缀节点。 该算法最初的解锁能力非常有限，因此在执行足够的解锁操作之前，它无法获得后续奖励。 堆会累积候选者，但仅在容量可用时才释放它们。 

对于第二种配置，其中所有高价值节点已经处于早期可到达位置，算法立即消耗它们，而不需要许多解锁操作，并且解锁计数器简单地确保一致性而不限制选择。 

这两种模式说明了不变量：在每一步，堆都包含所有可获得的奖励，并且解锁计数器保证我们永远不会选择比系统允许我们处理的更多的卡。

 ## 边缘情况

 当前几张卡的价值都很低，但对于解锁后面的簇是必需的时，就会出现严重的边缘情况。 该算法通过将它们存储在堆中但在解锁容量允许之前不消耗它们来处理此问题。 

另一个边缘情况是当所有高价值卡都已经可以提前到达时，在这种情况下，堆确保立即消耗，并且解锁计数器永远不会限制进度。 

当解锁链极其稀疏时，就会出现最终的边缘情况，迫使顺序解锁。 单调解锁计数器正确地模拟了该约束，防止过早选择深层节点。
