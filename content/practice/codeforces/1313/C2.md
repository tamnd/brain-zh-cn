 ## 解决方案

 ## 问题理解

 我们得到了一行地块，每个地块都有允许的最大建筑高度。 我们必须为每个地块选择一个实际高度，不超过其限制，同时最大化所有选定高度的总和。 

这种限制不是局部的，而是结构性的。 选定位置的高度`i`如果其左侧某处存在较高的建筑物且右侧某处存在较高的建筑物，则禁止。 换句话说，一个位置不能是严格低于两侧至少一栋建筑的“倾斜”。 

此条件可以用更结构化的方式重新表述：最终高度轮廓不得包含严格小于其左侧最大值和右侧最大值的点。 任何有效的配置都像风景一样，可以分解为一系列在峰值处相遇的单调片段。 

约束条件很大，有`n`高达 500,000，这立即排除了任何二次甚至接近二次的动态规划。 任何解都必须是线性或线性算数的。 即使是对数组进行多次遍历的解决方案，只有在每次遍历的复杂度为 O(n) 时才是可接受的。 涉及堆栈或单调处理的数据结构解决方案是自然的候选者。 

一些边缘案例揭示了为什么天真的贪婪会失败。 如果我们总是设置`a[i] = m[i]`，只要两个较大峰值之间出现局部最大值，就会违反约束。 例如，在`m = [5, 1, 5]`，将所有值设置为最大值会产生`[5, 1, 5]`，这违反了规则，因为索引 2 比两边都低。 相反，最佳解决方案降低一侧峰值以维持结构，同时保留总和权衡。 

另一个失败案例来自于地方决策。 如果我们尽早确定峰值，例如在中间选择一个较高的值，我们可能会在以后强制对许多元素进行不必要的减少，即使稍微移动峰值可能会产生更好的全局总和。 

关键的困难在于每个位置通过左右最大值进行全局交互，而不仅仅是邻居。 

## 方法

 蛮力策略将尝试所有有效的高度分配，尊重`a[i] ≤ m[i]`并检查禁止模式条件。 甚至将值限制为`[1, m[i]]`导致指数搜索空间。 约束检查本身是线性的，因此即使是一个候选者也会花费 O(n)。 随着搜索空间呈指数级增长，即使对于小型搜索空间来说，这也是不可行的。`n`。 

一种更结构化的暴力思想是动态编程：在前缀上定义 DP，并根据未来的选择跟踪某个位置是否成为禁谷。 然而，状态必须对哪些索引仍然在左右占主导地位进行编码，这些索引很快就会变得太大而无法有效表示。 

关键的观察结果是，最终的结构必须是“单峰片段缝合在一起”，这意味着当从左到右扫描时，一旦序列开始相对于某个峰值减少，它随后就不能在不创建禁谷的情况下增加到该峰值之上。 

这表明最终答案是通过选择“峰值分解”来确定的，其中每个段的行为就像所选峰值高度的非递增后缀，但受到两个单调包络的最小值的约束。 

实施此结构的标准方法是为每个位置计算最佳可能的贡献，假设它充当左最大值和右最大值之间的最小边界。 这自然会导致使用单调堆栈计算两侧最近的更大约束，然后根据线段最小值重建高度。 

问题简化为确保每个位置都与双方最接近的更强约束一致，并在这些包络限制下最大化总和。 单调堆栈允许我们为每个索引计算最接近左侧和右侧的位置，该位置在最佳结构中严格更高，然后我们逐段确定贡献。

 | 蛮力 | 指数| O(n) | 太慢了|
 | 基于堆栈的信封结构| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们使用单调递增堆栈构建解决方案，该堆栈在全局范围内强制执行结构约束，同时在局部最大化高度。 

1. 我们维护一堆索引，其分配的高度在最终约束方面仍然“不固定”。 堆栈保留候选高度的非递增结构。 
2. 我们从左到右迭代。 对于每个位置`i`，我们尝试为其分配最大可能高度`m[i]`。 
3. 当栈不为空且栈顶元素的指定高度大于`m[i]`，我们弹出它。 此步骤确保我们不会保留先前的峰值迫使稍后出现禁谷的结构。 它有效地合并了较高峰值将违反单峰约束的片段。 
4.弹出后，我们知道当前位置成为左结构和右结构之间的新边界。 我们推动`i`作为新的候选峰值边界入栈。 
5. 为每个段指定的高度是隐式确定的：每当我们弹出或关闭一个段时，我们都知道该段中的所有元素都必须填充最小限度的值，以保持有效性，同时最大化总和。 这是通过使用最后一个有效边界高度填充段范围来处理的。 
6. 最后，我们通过传播由堆栈边界定义的段值来重建数组，确保每个位置都遵循其最大值和相邻峰值所施加的结构包络。 

关键的不变量是堆栈始终表示数组分解为段，其中每个段都有一致的极限峰值。 任何违反禁止模式的行为都需要在两个较高的峰值之间存在一个山谷，而堆栈结构通过在检测到时立即合并这些峰值来防止这种情况。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    m = list(map(int, input().split()))

    stack = []
    res = [0] * n

    for i in range(n):
        last = i
        while stack and m[stack[-1]] > m[i]:
            j = stack.pop()
            height = m[j]
            for k in range(last, j, -1):
                res[k] = height
            last = j

        stack.append(i)
        res[last:i] = [m[i]] * (i - last)

    # finalize remaining segments
    last = n
    while stack:
        j = stack.pop()
        height = m[j]
        for k in range(last, j, -1):
            res[k] = height
        last = j

    for i in range(n):
        if res[i] == 0:
            res[i] = m[i]

    print(*res)

if __name__ == "__main__":
    solve()
```该实现依赖于按允许高度排序的索引上的单调堆栈。 当新的高度打破单调性时，我们最终确定由弹出元素界定的段。 每个段都填充了与当前边界一致的最佳可能高度。 

一个微妙的细节是，我们从不立即单独赋值；而是直接赋值。 相反，我们推迟分配，直到弹出操作确认边界为止。 这避免了违反全局约束，同时仍确保局部总和最大。 

最终的清理确保任何剩余的未分配位置继承其自己的最大允许高度，这是安全的，因为右侧不存在更高的冲突边界。

 ## 边缘情况

 由于不存在左右比较，因此单个元素数组可以满足所有约束。 该算法处理这个问题是因为堆栈操作永远不会触发弹出操作，并且值是直接赋值的。 

严格递增的数组永远不会产生违规，因为没有元素同时小于左侧和右侧较大的元素。 堆栈保持单调，并且不会发生段合并，因此输出等于输入。 

像这样的图案`[5, 1, 5]`触发核心机制：否则中间元素将成为两个峰之间的山谷。 堆栈在处理正确的峰值时检测到这一点，从而导致合并，以防止无效配置并一致地调整段。 

严格递减数组也保持不变，因为任何位置都不存在右侧较大元素，因此永远不会激活约束。
