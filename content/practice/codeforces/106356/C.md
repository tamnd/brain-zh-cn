 ## 解决方案
 ## 问题理解

 我们有一棵树$n$顶点，意义$n$巢相连$n-1$无向分支，任意两个巢之间只有一条简单路径。 除了这棵树之外，我们还得到了顶点的排列，它代表了乌鸦想要访问所有巢穴的确切顺序。 

目标是将给定的树转换为单个简单路径，其顶点以精确的排列顺序出现。 在最终的结构中，每个连续的对$p_i, p_{i+1}$必须由边直接连接，并且不允许有额外的边，因此得到的图恰好是覆盖所有顶点的链。 

我们被允许执行特殊的边缘重新布线操作。 在一次操作中，我们选择三个不同的顶点$a, b, c$使得边缘$(a,b)$和$(b,c)$目前存在。 我们删除边$(a,b)$并添加边缘$(a,c)$。 这有效地“滑动”$a$的连接来自$b$到$c$通过一个共同的邻居$b$，同时保留树结构。 

约束很小，有$n \le 300$每个测试用例和总计$\sum n^2$跨测试绑定。 这强烈表明解决方案涉及重复的最短路径计算、重复的树修改或$O(n^3)$-式的建设性程序是可以接受的。 

一种简单的方法是尝试直接将树全局重建为目标路径，但同时保持所有边的全局一致性是很困难的。 另一种失败模式是尝试尽早永久修复排列的一个片段，因为稍后的重新布线操作可能会使先前构造的边无效。 

当初始树已经是路径但排列顺序相反时，就会出现微妙的边缘情况。 如果不仔细推理重新布线对全局结构的影响，天真的“贪婪地修复相邻对”方法可能会反复破坏早期的正确边缘。 另一个有问题的情况是星形树，其中每个修复操作都会暂时增加其他连续对之间的距离。 

关键的困难在于，操作是沿着长度为 2 的路径进行本地重新布线，但目标是全局的：强制执行所有操作$n-1$同时需要邻接。 

## 方法

 暴力思维会尝试重复修改树，直到它与目标路径匹配。 一个直接的尝试是，对于每一连续对$p_i, p_{i+1}$，计算它们在当前树中的路径，然后重复“缩短”该路径，直到它们变得相邻。 快捷步骤需要三个连续的顶点$x_{j-1} - x_j - x_{j+1}$并替换边缘$(x_{j-1}, x_j)$和$(x_{j-1}, x_{j+1})$,有效去除$x_j$从端点之间的路径内部。 

这个想法在本地是正确的，因为每个这样的操作都会严格减少所选对之间的距离。 但是，如果我们尝试在移动到下一个之前永久修复一对，则后续操作可能会破坏较早的边缘，因此我们不能依赖单次传递。 

关键的观察是我们实际上不需要保留中间正确性。 最终的结构是一棵树$n-1$边缘。 如果我们确保排列中的每个连续对都由末尾的边连接，那么那些$n-1$边必须正是最终的树，这迫使它成为所需的路径。 因此，我们只需要重复强制连续对的邻接性，直到所有对都同时满足。 

这允许一个简单的势驱动过程：每当连续对不相邻时，我们就使用沿其独特路径允许的操作来缩短它们的距离。 每次操作至少将距离减少一，并且$n \le 300$，此类减少的总数仍然在舒适的范围内$O(n^2)$运营。

 ## 算法演练

 我们维护当前的树并重复强制连续排列对的邻接。 

1. 从给定的树和排列开始$p$。 该树在每次操作后始终有效，因为每次重新连线都会保留连接性和边数。 
2. 迭代索引$i = 1$到$n-1$, 对待这对$(p_i, p_{i+1})$。 每对的目标是使它们直接连接。 
3.如果$p_i$和$p_{i+1}$已经在当前树中相邻，不执行任何操作并继续前进。 否则，计算它们之间的唯一路径，例如$$x_0 = p_i, x_1, \dots, x_k = p_{i+1}.$$4. 沿着这条路径，重复选取任何内部线段$x_{j-1} - x_j - x_{j+1}$并应用该操作$a = x_{j-1}, b = x_j, c = x_{j+1}$。 这消除了边缘$(x_{j-1}, x_j)$并添加$(x_{j-1}, x_{j+1})$，将路径缩短一个顶点。 
5. 继续缩短直到之间的路径$p_i$和$p_{i+1}$长度为一，意味着它们现在相邻。 
6. 对所有连续的对重复此过程，直到每对都相邻。 

处理完所有对后，我们输出所有记录的操作。 

### 为什么它有效

 每个操作都会严格减少所选对之间的距离$(p_i, p_{i+1})$。 由于树中的距离是有限的，因此每对树在经过有限多个步骤后就会变得相邻。 

关键的结构事实是，一旦排列中的每个连续对都由一条边连接，我们就可以准确地得到$n-1$总计边数。 树不能包含循环，因此这些边必须形成单个哈密顿路径。 排列顺序迫使该路径准确无误$p_1 \rightarrow p_2 \rightarrow \dots \rightarrow p_n$，因为每个顶点在最终边集中都有完全正确的邻居。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import deque

def bfs_path(adj, s, t):
    parent = {s: -1}
    q = deque([s])
    while q:
        u = q.popleft()
        if u == t:
            break
        for v in adj[u]:
            if v not in parent:
                parent[v] = u
                q.append(v)

    path = []
    cur = t
    while cur != -1:
        path.append(cur)
        cur = parent[cur]
    path.reverse()
    return path, parent

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        adj = [[] for _ in range(n + 1)]
        edges = set()

        for _ in range(n - 1):
            u, v = map(int, input().split())
            adj[u].append(v)
            adj[v].append(u)
            edges.add(tuple(sorted((u, v))))

        ops = []

        def remove_edge(a, b):
            adj[a].remove(b)
            adj[b].remove(a)
            edges.discard(tuple(sorted((a, b))))

        def add_edge(a, b):
            adj[a].append(b)
            adj[b].append(a)
            edges.add(tuple(sorted((a, b))))

        def dist(u, v):
            q = deque([u])
            seen = {u}
            parent = {u: -1}
            while q:
                x = q.popleft()
                if x == v:
                    break
                for y in adj[x]:
                    if y not in seen:
                        seen.add(y)
                        parent[y] = x
                        q.append(y)
            return parent

        def get_path(u, v):
            parent = dist(u, v)
            path = []
            cur = v
            while cur != -1:
                path.append(cur)
                cur = parent[cur]
            return path[::-1]

        for i in range(n - 1):
            while True:
                path = get_path(p[i], p[i + 1])
                if len(path) == 2:
                    break

                a, b, c = path[0], path[1], path[2]

                # operation (a, b, c)
                ops.append((a, b, c))
                remove_edge(a, b)
                add_edge(a, c)

        print(len(ops))
        for a, b, c in ops:
            print(a, b, c)

if __name__ == "__main__":
    solve()
```该实现重复地重新计算连续排列元素之间的当前路径。 一旦路径长度超过 2，它将采用该路径上的前三个顶点并执行绕过中间顶点的允许旋转。 这保证了路径每次都会缩短一条边。 

邻接列表是动态更新的，因此未来的路径计算反映了当前的树。 最后存储并打印操作列表。 

一个微妙的点是，重新计算 BFS 路径在这里是安全的，因为$n \le 300$，所以即使重复$O(n)$循环内的 BFS 仍处于限制范围内。

 ## 边缘情况

 最小二节点树没有内部顶点，因此算法立即检测邻接并且不执行任何操作。 该结构仍然有效，因为没有触发 BFS 缩短。 

星形树展示了通过中心枢纽的反复重新路由。 每个操作都会从路径中间删除一个叶子附件，并将其重新附加到更靠近目标端点的位置，并且 BFS 重新计算确保我们始终对更新的结构进行操作。 

反向链迫使算法重复翻转内部段。 每个步骤都会缩短一个三节点路径段，直到实现邻接，这表明该方法不依赖于初始方向或结构。
