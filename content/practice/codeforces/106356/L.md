 ## 解决方案
 ## 问题理解

 我们正在模拟一条蛇在$n \times n$边缘环绕的网格，因此网格的行为就像一个环面。 蛇开始时是一个单细胞$(1,1)$。 我们得到一个序列$k$移动，每次将头部朝基本方向移动一步，如果出界则应用环绕。 

在每一步中，头部移动后，如果头部落在当前食物单元上，我们要么让蛇生长，要么通过向前移动尾巴来保持长度不变。 食物按照固定的顺序一件一件地出现：任何时候都只有一种食物，当前一种食物被吃完后，下一种食物就会立即出现。 重要的是，如果蛇在移动头部后落在身体的任何部位，就会死亡，但只有当尾巴在同一步骤中同时移开时，才允许进入当前的尾部单元。 

任务是确定蛇是否能幸存下来$k$移动。 如果它死得更早，我们输出`DEAD`，否则我们输出`ALIVE`接下来是它的最终长度。 

约束条件达到$10^5$对于所有参数，这立即排除了任何每次移动都会扫描蛇整个身体的方法。 通过在每一步迭代整个身体来检查碰撞的简单模拟将花费$O(k^2)$在最坏的情况下，这太慢了。 我们需要对每次移动进行常数或对数摊销操作。 

一个微妙的问题来自“尾部例外”规则。 如果蛇没有生长，尾巴会在头部移动后离开，因此进入旧的尾部细胞是安全的。 在不考虑这个时间的情况下检查与整个身体的碰撞的幼稚方法会错误地将一些有效的动作标记为死亡。 

另一个微妙的边缘情况来自环绕。 例如，在一个$3 \times 3$网格，从第 1 列向左移动到第 3 列。如果在应用模块化标准化之前实现碰撞逻辑，则可能会错误地检测出越界状态。 

最后，进食时间很重要：蛇在着陆时立即生长，这意味着尾巴在这一步中不会移动。 这会改变下一步动作的碰撞规则，因为身体形状与无生长情况不同。 

## 方法

 蛮力的想法很简单：维护从头到尾的所有蛇体细胞的显式列表或双端队列。 对于每次移动，我们计算新的头部位置，然后扫描整个身体以检查头部是否与任何部分发生碰撞。 如果没有碰撞，我们要么追加新的头部并删除尾部（如果没有食物），要么只追加头部（如果有食物）。 这是正确的，因为它直接模拟了规则。 

然而，这种方法变得太慢，因为每个步骤可能需要扫描最多$O(k)$身体各部分，导致$O(k^2)$蛇线性增长时的总功。 和$k = 10^5$，这的顺序是$10^{10}$检查，这远远超出了限制。 

关键的观察是我们实际上不需要显式地存储或扫描整个身体。 我们只需要两个操作：检查一个单元格当前是否被蛇占据，并随着蛇的移动插入或删除单元格。 这建议为占用的单元维护一个哈希集，并为有序主体维护一个双端队列，以便我们可以有效地删除尾部。 

唯一的复杂之处是处理“尾部同时移动”规则。 我们必须确保在检查碰撞时，如果尾部单元会在同一步中移动，则暂时忽略它。 这意味着在检查占用率之前，我们必须确定蛇是否正在生长，如果它没有生长，我们在执行碰撞测试之前从概念上将尾巴从占用集中删除。 

通过这种结构，每次移动都以摊销方式处理$O(1)$，因为 deque 和 set 上的所有操作都是恒定的平均时间。

 ## 算法演练

 我们维护两个结构：一个存储蛇体从头到尾的双端队列，以及一个存储所有占用单元格的哈希集，用于快速成员资格查询。 

### 步骤

 1.用单个cell初始化蛇$(1,1)$在 deque 和 set 中，并将食物索引设置为 0。当前食物是列表中的第一项。 
2. 对于每次移动，使用方向计算下一个头部位置，应用环绕模数$n$。 这可确保所有坐标保持在有效范围内。 
3. 确定新的头部位置是否等于当前的食物单元。 这决定了蛇在这一招中是否会成长。 
4. 如果蛇没有生长，则在检查碰撞之前从集合中删除当前的尾部单元。 这模拟了尾巴与头部同时移开的事实。 
5. 检查集合中是否已存在新的头单元。 如果发生了，蛇会立即死亡，因为它在当前配置中与其身体发生碰撞。 
6. 否则，将新的头单元添加到双端队列的前面并将其插入到集合中。 
7. 如果食物被吃掉，通过不去除尾巴来增加长度并前进到下一个食物。 如果没有吃食物，则在插入逻辑解决后从双端队列中删除尾部单元。 

一个微妙的订购点是，必须根据正确的状态检查碰撞：要么移除尾巴（非生长的情况），要么完整的身体（生长的情况）。 

### 为什么它有效

 不变的是，在每次移动开始时，双端队列和集合准确地代表了蛇在之前所有移动之后的身体。 在处理移动时，我们通过在碰撞检测之前仅在非生长情况下暂时删除尾部来正确模拟头部和尾部的同时移动。 这确保了占用检查反映了蛇在头部移动时的真实物理状态。 由于每次更新都会保持双端队列和集合之间的一致性，因此不会保留过时的位置，并且每次碰撞都准确对应于模拟中的真实自相交。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k, m = map(int, input().split())
s = input().strip()

food = [tuple(map(int, input().split())) for _ in range(m)]

from collections import deque

snake = deque()
snake.append((1, 1))

occupied = set()
occupied.add((1, 1))

head_x, head_y = 1, 1
food_idx = 0

dir_map = {
    'L': (0, -1),
    'R': (0, 1),
    'U': (-1, 0),
    'D': (1, 0)
}

for ch in s:
    dx, dy = dir_map[ch]
    nx, ny = head_x + dx, head_y + dy

    if nx == 0:
        nx = n
    elif nx == n + 1:
        nx = 1
    if ny == 0:
        ny = n
    elif ny == n + 1:
        ny = 1

    eat = (food_idx < m and (nx, ny) == food[food_idx])

    if not eat:
        tx, ty = snake[-1]
        occupied.remove((tx, ty))

    if (nx, ny) in occupied:
        print("DEAD")
        sys.exit(0)

    snake.appendleft((nx, ny))
    occupied.add((nx, ny))
    head_x, head_y = nx, ny

    if eat:
        food_idx += 1
    else:
        snake.pop()

print("ALIVE", len(snake))
```代码直接遵循仿真模型。 双端队列将蛇从左侧的头部存储到右侧的尾部。 该集合镜像它以进行 O(1) 碰撞检查。 关键的微妙之处在于，当蛇没有生长时，在进行碰撞检查之前将尾巴从集合中移除，从而正确地模拟同时运动。 

应用移动后，通过边界检查显式处理环绕。 这避免了依赖于在极端情况下可读性稍差的模算术。 

在修改身体之前检查食物消耗，以便在同一动作中立即应用生长。

 ## 边缘情况

 一种重要的边缘情况是在不生长时进入尾部细胞。 例如，一条长度为 3 的蛇向前移动到自己的尾巴位置，如果同时移除尾巴，则该蛇不会死亡。 在非增长步骤中进行碰撞检查之前，该实现显式地从占用集中删除尾部，以确保正确处理这种情况。 

另一个边缘情况是环绕时立即食用食物。 如果头部从$(1,1)$如果留在小网格上，它可能会绕到另一侧并恰好落在食物细胞上。 由于食物检查是在坐标标准化后完成的，因此这种情况正确地触发了生长。 

最后一个边缘情况是增长后的自碰撞。 当蛇吃食物时，尾巴是不动的，所以被占领的集合一定不能把尾巴移开。 这使得主体立即变长一个单元，并且与该扩展主体的任何碰撞都会被正确检测到，因为我们在这种情况下检查完整的占用集。
