 ## 解决方案
 ## 问题理解

 我们有一条笔直的道路，几个加油站的位置逐渐增加。 每个加油站每升燃油都有固定的价格。 汽车从位置 0 开始，油箱是空的，油箱容量有限，总预算固定。 

汽车在任何车站只能购买整升，并且每升只能行驶一个单位的距离。 向前行驶时，汽车可能会在经过的任何站点停下来，在剩余预算和油箱容量内购买燃料，然后继续前进。 目标是确定如果选择最佳购买，汽车可以沿着道路行驶多远。 

关键的困难在于，决策是地方性的，但会产生全球性的后果：过早购买太多昂贵的燃料可能会阻碍以后到达更便宜的加油站，而过早省钱可能会导致燃料不足，无法通过加油站之间的长距离。 

输入大小高达 100,000 个站点，位置高达 10^9，预算和容量高达 10^9。 这排除了任何模拟每个旅行单位或尝试所有购买组合的策略。 任何解决方案都必须在大致线性或线性对数时间内处理每个站点。 

一个微妙的边缘情况来自车站之间的长间隙。 即使总预算总体上是足够的，但大于油箱容量的缺口也会使进一步的旅行变得不可能，除非汽车能够策略性地加满油箱到达。 另一种边缘情况是，最后一个可到达的站点不一定是预算或燃料耗尽的站点，而是下一个间隙变得太大之前的站点。 

仅在当前站点贪婪地购买而不考虑未来价格的幼稚方法可能会失败。 例如，如果一个便宜的电台后面跟着一个稍微贵一点的电台，但随后价格差距很大，那么过早过度购买可能会浪费以后弥补差距所需的预算。 

## 方法

 蛮力方法将逐步模拟旅程，维持当前燃料和剩余预算，并在每个站点根据当地情况决定购买多少燃料。 在每一步中，我们都会考虑从零到剩余容量的所有可行购买量，并递归地评估每个选择的领先程度。 这立即变得不可行，因为在每个站点我们有最多 C 个选择，并且我们可能遍历最多 n 个站点，导致指数或至少 O(nC) 行为，这远远超出了限制。 

关键的见解是我们不需要模拟每升决策。 重要的是，除了价格之外，燃料是可以互换的，并且汽车只能从更便宜的加油站购买燃料并同时遵守容量限制中受益。 这将问题转化为一个贪婪的“资源积累”过程，在这个过程中，我们维持理想情况下想要携带的燃料量，受油箱容量和剩余预算的限制。 

我们不是独立地考虑每个站点的购买决策，而是将站点之间的移动视为已知距离的间隔。 对于连续站点之间的每个航段，我们必须确保我们能够支付并携带足够的燃料来覆盖该距离。 如果以后有更便宜的燃料可用，最佳策略总是避免购买昂贵的燃料，但由于我们不明确地知道未来，因此我们在跟踪全球约束的同时模拟可行性。 

这导致我们保持当前的燃料、剩余预算，并确保在每个路段我们都能覆盖所需的距离。 当燃油不足时，我们必须“追溯”在以前的加油站购买燃油，但仅限于其价格和容量限制。 这自然可以通过在需要时优先考虑更便宜的早期购买来解决。

 | --- | --- | --- | --- |
 | 购买决策的强力模拟| 指数或 O(n·C) | O(1)-O(n) | O(1)-O(n) | 太慢了 |
 | 具有有限燃料和预算跟踪的贪婪前向模拟 | O(n) | O(1)-O(n) | O(1)-O(n) | 已接受 |

 ## 算法演练

 1. 我们按照位置递增的顺序处理站点，将连续站点之间的每个间隙视为必须遍历的段。 这将连续的道路转换为离散的所需出行成本。 
2. 在每个站点，我们计算到达下一站点需要多少燃料。 如果当前燃料不足，我们会尝试在当前加油站购买燃料，但受到剩余预算和油箱容量的限制。 
3. 我们可以购买的数量受到坦克剩余空间和我们还有多少钱的限制。 我们总是只购买继续发展所必需的东西，因为过度购买无助于未来的限制，除非它可以防止当前细分市场的资源耗尽。 
4. 确保当前航段有足够的燃料后，我们从油箱中减去该航段的距离并继续前进。 
5. 我们重复此过程，直到我们处理完所有站点，或者达到即使在尽可能多地填充油箱后也无法支付下一段费用的程度。 
6.每当我们成功通过车站或路段时，最远可达距离就会更新。 

### 为什么它有效

 关键的不变量是，在进入站 i 和 i+1 之间的每个段之前，算法维护在站 i 处可以累积的最大可行燃料，而不会超出油箱容量或预算限制。 因为燃料仅受容量和花费的总资金的限制，并且因为所有未来的决定仅取决于我们是否能够在即将到来的距离中生存，而不取决于如何获取燃料，所以这种对可行燃料的贪婪维护就足够了。 任何偏离此的替代策略要么会违反容量，要么会在不提高可达性的情况下提前花费更多预算，因此它无法将最终可达距离扩展到超出此模拟所实现的范围。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, B, C = map(int, input().split())
    x = []
    p = []
    for _ in range(n):
        xi, pi = map(int, input().split())
        x.append(xi)
        p.append(pi)

    fuel = 0
    money = B
    pos = 0

    for i in range(n - 1):
        dist = x[i + 1] - x[i]

        if fuel < dist:
            need = dist - fuel

            can_buy = min(need, C - fuel)

            cost = can_buy * p[i]

            if cost > money:
                can_buy = money // p[i]
                cost = can_buy * p[i]

            fuel += can_buy
            money -= cost

        if fuel < dist:
            pos = x[i] + fuel
            print(pos)
            return

        fuel -= dist
        pos = x[i + 1]

    print(pos)

if __name__ == "__main__":
    solve()
```该实现在站点之间移动时跟踪剩余燃料和剩余预算。 在每个路段，它确保有足够的燃料可用，仅以当前加油站的价格购买，并尊重油箱容量和剩余资金。 如果即使在最大可行购买后仍无法覆盖下一段，则该过程将停止，并根据当前位置加上剩余燃料计算准确的可到达坐标。 

一个常见的错误是忽视燃料采购同时受到容量和预算的限制。 另一种假设是贪婪地购买直至满箱总是最佳的； 当预算紧张并且早期的超额购买阻止了以后的必要购买时，这种情况就会被打破。

 ## 边缘情况

 一个关键的边缘情况是，由于容量或预算较低，第一个部分已经超出了 1 号站的购买量。 在这种情况下，算法会立即计算出只能到达距起点的部分距离，因为未来的站点无法提供追溯帮助。 

另一种极端情况是储罐容量小于站之间的单个段。 即使预算无限，汽车也无法穿越这个间隙，因此算法会正确地停在最后一个可到达的车站边界，而无需尝试进一步购买。 

当最后一站之后仍有预算时，就会出现第三种边缘情况。 该算法通过将剩余燃料转换为距离来自然地扩展覆盖范围，因为未来没有限制限制超出最后一段的移动。
