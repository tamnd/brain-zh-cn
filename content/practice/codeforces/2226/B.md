 ## 解决方案
 ## 问题理解

 我们得到了整数的排列`1`到`n`。 对于每个连续的子数组，我们查看三个数量：

 - 其最大值，
 - 其最小值，
 - 其中所有值的 GCD。 

当一个子数组被称为好的子数组时$$\max - \min = \gcd(\text{all elements})$$任务是计算有多少子数组满足这个条件。 

第一直觉是检查每个子数组并计算其最小值、最大值和 GCD。 这很快就变得不可能了。 排列的长度可达`2·10^5`，所有测试用例的长度总和也是`2·10^5`。 任何检查所有的解决方案`O(n^2)`即使在考虑计算 GCD 和极值的成本之前，子数组已经太慢了。 

这个问题有趣的部分是数组是一个排列。 每个值都是不同的。 这种限制使情况变得比最初出现的情况要严重得多。 

一个常见的错误是假设更长的子数组可能满足条件。 考虑子数组`[2,4,6]`。 其最大值减去最小值为`4`，而其 GCD 为`2`，所以这样不好。 更重要的是，在排列中，任何长度至少为 3 的良好子数组实际上都是不可能的，原因我们稍后会推导。 

另一个容易犯的错误是忘记单元素子数组永远都不好。 例如，`[5]`有$$\max - \min = 0$$但$$\gcd(5)=5.$$条件不成立。 

暴露真实结构的一个小例子是`[2,1]`。$$\max-\min = 1, \qquad \gcd(2,1)=1.$$这个子阵不错。 同样的情况也发生在`[4,2]`:$$\max-\min = 2, \qquad \gcd(4,2)=2.$$这些例子暗示只有成对的形式`(x,2x)`可以工作。 

## 方法

 暴力解决方案检查每个子数组。 对于每一个，计算其最小值、最大值和 GCD，然后测试条件。 有`O(n^2)`子数组。 即使范围信息是增量维护的，总工作量仍然至少是二次的。 和`n = 2·10^5`，这大约意味着`4·10^10`最坏的情况下是子数组，这是完全不可行的。 

为了更快地找到东西，我们需要了解条件意味着什么。 

假设一个子数组是好的，它的 GCD 是`g`。 

由于 GCD 划分了每个元素，因此子数组中的每个元素都是`g`。 

条件说$$\max - \min = g.$$设最小值为`m`。 因为`g`划分每个元素，它划分`m`。 那么最大值就是`m + g`。 

现在看看区间`[m, m+g]`。 其中的倍数为`g`，这个区间只包含两个值：$$m,\quad m+g.$$子数组的每个元素都必须是`g`，并且每个元素都必须位于最小值和最大值之间。 只剩下这两个值了。 

因为数组是一个排列，所以值是不同的。 子数组不能包含任一值的重复副本。 

所以一个好的子数组最多可以包含两个元素。 

长度一是不可能的，因为`max-min=0`而 GCD 为正值。 因此，每个好的子数组都恰好有两个元素。 

让这两个值是`a < b`。 

条件变为$$b-a=\gcd(a,b).$$让这个共同的价值观成为`g`。 然后$$a=gk,\qquad b=g(k+1).$$由于连续整数互质，$$\gcd(a,b)=g\cdot\gcd(k,k+1)=g.$$结合这与`b-a=g`给出$$a=g,\qquad b=2g.$$所以这对必须是完全一样的`(g,2g)`。 

整个问题归结为计算值呈加倍关系的相邻位置。

 | --- | --- | --- | --- |
 | 蛮力 | O(n²) 或更糟 | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将答案初始化为零。 
2. 扫描每一个相邻的对`(p[i], p[i+1])`。 
3.让`x = min(p[i], p[i+1])`和`y = max(p[i], p[i+1])`。 
4. 检查是否`y = 2x`。 

这正是上面导出的特征。 任何好的子数组都必须有长度二，并且它的值必须是`(x,2x)`。 
5. 如果条件成立，则增加答案。 
6. 处理完所有相邻对后，输出答案。 

### 为什么它有效

 我们证明了每个好的子数组的长度必须恰好为 2。 原因是所有元素都是子数组GCD的倍数`g`，而最小值和最大值之间的距离仅为`g`。 该区间仅包含两个倍数`g`，即最小值和最大值本身。 

对于具有值的二元素子数组`a < b`，条件变为$$b-a=\gcd(a,b).$$这个方程成立当且仅当`b=2a`。 

该算法精确计算那些相邻的对。 每个计数的对都是好的，并且每个好的子数组都必须是这些对之一。 因此计数是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        cur = 0
        for i in range(n - 1):
            a = p[i]
            b = p[i + 1]

            if max(a, b) == 2 * min(a, b):
                cur += 1

        ans.append(str(cur))

    sys.stdout.write("\n".join(ans))

solve()
```解决方案直接遵循数学特征。 

该循环仅检查相邻对，因为每个好的子数组的长度都是二。 对于每一对，我们通过取较小和较大的值对其进行标准化。 当较大值是较小值的两倍时，这对就很好。 

使用`max(a,b) == 2 * min(a,b)`自动处理两个订单，所以两个`[x,2x]`和`[2x,x]`被计算在内。 

最终实现中不需要GCD计算。 数论分析完全消除了它。

 ## 边缘情况

 ### 单元素子数组

 考虑：```
[5]
```天真的推导可能会忘记长度为一的子数组。 

这里：$$\max-\min=0, \qquad \gcd=5.$$条件不成立。 我们的算法从不计算它们，因为它只检查相邻对。 

### 逆序加倍对

 输入：```
n = 2
p = [4,2]
```该对满足：$$4-2=2, \qquad \gcd(4,2)=2.$$即使较大的值优先，这也很好。 

实现使用：```
max(a, b) == 2 * min(a, b)
```因此两个订单的处理方式相同。 

### 看起来有希望的更长子数组

 考虑：```
[2,4,6]
```所有值都是以下的倍数`2`，这可能会诱使某人认为子数组很好。 

现实中：$$\max-\min=4, \qquad \gcd=2.$$条件不成立。 

证明表明了一些更强有力的东西：长度至少为 3 的子数组不可能在排列中表现良好。 这就是为什么仅检查相邻对就足够了。 

### 差值等于 1 的对

 考虑：```
[2,3]
```区别在于`1`， 但$$\gcd(2,3)=1.$$这对不是以下形式`(x,2x)`，但它仍然满足方程：

 等等，我们来验证一下：$$3-2=1, \qquad \gcd(2,3)=1.$$这实际上是一对很好的搭档。 自从`x=1`，表征给出值`(1,2)`， 不是`(2,3)`。 

错误在于假设仅存在差异就足够了。 条件要求与 GCD 相等。 为了`[2,3]`，这对确实很好，因为 GCD 是`1`。 

回顾一下二元数组的推导：$$b-a=\gcd(a,b).$$让`g = gcd(a,b)`。 写作`a=gk`和`b=g(k+1)`力量`k=1`， 因此`a=g`和`b=2g`。 

为了`[2,3]`，我们有`g=1`， 但`a=2`， 不是`1`，所以表征表明它应该不好。 直接检查：$$3-2=1,\quad \gcd(2,3)=1.$$该条件实际上成立。 

这揭示了关键的代数步骤：

 来自$$a=gk,\quad b=g(k+1),$$我们得到$$b-a=g$$自动为每个`k`，不仅对于`k=1`。 

因此，二元素子数组的真实特征是：$$\gcd(a,b)=|a-b|.$$出租`a=gk`和`b=g(k+1)`表明这对于连续倍数始终成立`g`。 

因为数组是一个排列，所以一个好的子数组仍然只能有长度二，但配对条件变成$$\max(a,b)-\min(a,b)=\gcd(a,b).$$对于排列，这意味着直接计算满足该方程的相邻对。 

最终接受的实现应使用：```
from math import gcd

if abs(a - b) == gcd(a, b):
    ans += 1
```因为成对喜欢`[2,3]`也有效。
