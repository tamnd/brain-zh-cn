 ## 解决方案
 ## 问题理解

 我们得到一个正整数序列。 我们反复删除元素组，直到什么都没有留下。 每个组必须遵守两个约束：如果我们以升序查看所选索引，则相应的值必须是非递减的，并且索引本身必须像往常一样对于子序列严格递增。 删除一个组的成本是其内部所有值的乘积，我们希望所有组的总成本尽可能小。 

关键的自由在于我们不会被迫删除连续的片段； 我们可以选择任何子序列，只要按索引顺序读取时其值不减少即可。 这意味着我们有效地将数组划分为几个有效的子序列，并且每个元素恰好属于一个子序列。 目标仅取决于我们如何将值分组在一起，因为成本在每个组内纯粹是乘法，而在组之间是加法。 

约束很小：数组最多有 100 个元素，值最多有 100 个。这立即表明位置上的二次或三次动态规划是合理的，而子集上的任何指数则不然。 

当分组有益时，即使它增加了局部的乘法成本，也会出现一种幼稚但重要的边缘情况。 例如，值`[1, 2, 2]`可以单独购买，需支付费用`1 + 2 + 2 = 5`，但将它们分组为一个有效的非递减子序列会产生成本`1 * 2 * 2 = 4`。 这表明问题不是一个简单的“避免将数字相乘”的启发式问题； 尽早对小值进行分组可以降低总成本。 

另一个微妙的问题是可行性取决于索引顺序，而不仅仅是值。 例如，`[2, 1]`即使排序值会建议，也不能将它们分组在一起，因为子序列顺序会强制减少。 

## 方法

 蛮力的想法是尝试一切可能的方法将数组划分为有效的子序列。 对于每个分区，我们将验证每个组是否按索引顺序形成一个非递减序列并计算其成本。 分区的数量像贝尔数一样增长，甚至仅限于有效子序列，它仍然呈指数增长`n`。 和`n = 100`，这是完全不可行的。 

问题的结构表明了一种贪婪的观点：每次我们形成一个子序列时，我们都在决定如何链接元素，以便值在该链内永远不会减少。 一旦将一个元素分配给一条链，它的贡献就会乘以锁定该链的成本。 这使得元素之间的交互成为局部的，因为在链的早期添加一个小值可以减少后来的乘法增长。 

关键的观察结果是，成本函数会奖励尽可能将小值分组在一起，因为乘以大于 1 的值会很快增加成本。 同时，分组受到沿指数的非递减约束的限制，这有效地迫使链尊重位置和价值顺序。 

这导致了一种建设性的贪婪策略：我们从左到右重复构建有效的子序列，每当可以附加下一个可用元素而不破坏非递减顺序时，总是扩展子序列，并在不能时启动新的子序列。 这相当于在每次运行遵循子序列规则的约束下将数组划分为最少数量的“局部递增”运行，然后对每次运行的乘积求和。

 ## 算法演练

 1. 从左到右扫描数组，同时保持当前正在构建的子序列。 我们还维护添加到该子序列的最后一个值。 
2. 对于每个元素，检查它是否可以在不破坏非减条件的情况下扩展当前子序列。 如果可以，将其附加到当前子序列并更新正在运行的产品。 
3. 如果无法扩展子序列，则关闭当前子序列，将其乘积添加到答案中，并从当前元素开始开始一个新的子序列。 
4. 继续直到所有元素都消耗完，然后添加最终子序列的乘积。 

这种构造有意义的原因是每个子序列在索引顺序的非递减约束下得到最大扩展，因此段内不会留下未使用的局部有效扩展。 

### 为什么它有效

 该算法根据贪婪扩展规则将数组构造为最大有效子序列。 任何时候我们停止一个子序列，都是因为下一个元素严格小于最后选择的元素，这意味着它不能属于同一个子序列而不违反可行性。 这确保每个子序列都是有效的。 

在每个子序列中，提前扩展而不是开始新的子序列永远不会增加贪婪构造的成本，因为开始新的子序列会强制使用单独的乘法因子，而不是共享现有的乘积结构。 因此，贪婪分割避免了不必要的碎片，同时尊重可行性约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 676767677

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ans = 0
        
        i = 0
        while i < n:
            cur_prod = a[i]
            last = a[i]
            j = i + 1
            
            while j < n and a[j] >= last:
                cur_prod = (cur_prod * a[j]) % MOD
                last = a[j]
                j += 1
            
            ans = (ans + cur_prod) % MOD
            i = j
        
        print(ans)

if __name__ == "__main__":
    solve()
```该实现独立地处理每个测试用例，并从当前位置开始重复构造最大非递减段。 变量`cur_prod`跟踪当前子序列的乘法成本，同时`last`强制执行非递减约束。 一旦约束被打破，子序列就会被关闭，其成本将被累积到全局答案中。 

这里的一个常见实施陷阱是在启动新的子序列时忘记重置正在运行的产品和最后值跟踪器。 另一个微妙之处是每一步的模乘法，因为中间乘积甚至可以超过 64 位限制`n ≤ 100`。

 ## 边缘情况

 关键的边缘情况是严格递减的数组，例如`[5, 4, 3, 2]`。 该算法立即关闭单个元素之后的每个子序列，因为不可能进行扩展。 每个元素形成自己的组，总成本变为`5 + 4 + 3 + 2`。 

另一种情况是完全非减数组，例如`[1, 1, 1, 1]`。 贪心构造不断扩展单个子序列，产生成本`1 * 1 * 1 * 1 = 1`。 任何人为的分裂只会增加乘法组的数量，并不能降低成本。 

混合情况，例如`[2, 1, 3]`清楚地显示重启行为：`[2]`立即关闭，然后`[1, 3]`形成一个有效的子序列，产生总成本`2 + 3 = 5`。
