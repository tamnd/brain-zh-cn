 ## 解决方案
 ## 问题理解

 我们得到了一个模式字符串`S`和一个文本字符串`T`。 从`T`，我们考虑每个连续的子串。 对于每个这样的子串`X`，我们计算其编辑距离`S`，表示将一个字符串转换为另一个字符串所需的插入、删除或替换的最少次数。 

我们不是要求单个答案，而是要求计算有多少个子串`T`有准确的距离`0`， 确切地`1`，依此类推，直到`k`。 两个子字符串通过位置来区分，因此出现在不同位置的相同字符序列分别做出贡献。 

关键的规模问题来自输入大小。 两个都`S`和`T`最多可达 100,000 个字符，并且`k`最多 30。 之间的直接动态规划比较`S`和每个子串`T`将需要对二次数量的子串边界进行重复计算，这是立即不可行的。 即使是单个 Levenshtein DP`O(|S||T|)`，并且对每个子字符串执行此操作远远超出了任何限制。 

一个天真的想法是独立处理每个子串并通过 DP 计算编辑距离。 另一个常见的错误是尝试在不限制状态空间的情况下滑动窗口并更新 DP，这会悄然中断，因为编辑距离在允许恒定时间更新的扩展下不是单调的。 

暴露错误推理的一个小边缘情况是`S = "a"`和`T = "aaaa"`。 子串是`"a"`,`"aa"`,`"aaa"`,`"aaaa"`等。距离为`0`,`1`,`2`,`3`等等。任何假设只有相等长度的子串的方法都会立即失败，因为插入和删除占主导地位。 

另一个边缘情况是当`S`比子串长得多。 例如，`S = "abcde"`和`X = "a"`。 距离不是 4，而是 4 个删除，但根据比对，替换可能会更便宜。 任何仅基于长度差异的推理都会错过替换结构。 

主要困难是我们必须处理`T`同时保持编辑距离计算局部化并受以下限制`k`。 

## 方法

 暴力解决方案修复子串`[l, r]`的`T`并计算编辑距离`S`使用标准DP。 每个这样的计算成本`O(|S| * (r-l+1))`或者如果天真地做更糟，并且有`O(|T|^2)`子串。 这会导致最坏情况的复杂性`O(n^3)`，这对于`n = 10^5`。 

即使我们将每个子串的 DP 优化为`O(|S| * k)`通过截断对角线，子串的数量仍然是二次的，因此我们仍然超出了几个数量级的限制。 

关键的结构观察是我们永远不需要大于`k`。 一旦编辑距离超过`k`，我们所关心的是它“太大”，我们可以停止跟踪该状态。 这将完整的动态规划表转换为带限过程。 

我们不是独立计算每个子串的距离，而是反转观点：我们固定一个起始位置`T`，并逐渐延伸右端点。 对于每个起始位置，我们维护一个 DP 状态来跟踪之间的编辑距离`S`和当前的子字符串前缀`T`，但仅限于有界宽度范围内`k`。 

这将问题转化为在滑动窗口上维护滚动编辑距离 DP`T`，进行超距离修剪`k`。 DP状态的演变`O(k)`每个字符扩展名，我们只计算当前最佳距离落在以下范围内的子串`[0, k]`。 

关键是Levenshtein DP只依赖于三个转换：插入、删除、替换。 当我们将注意力限制在成本≤ k 的状态时，我们只保留 DP 矩阵的一个窄对角带，因为任何漂移太远的对齐都会导致太多编辑。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2 * | S | ) |
 | 带限滚动DP | O(n * k) | O(k) | 已接受 |

 ## 算法演练

 我们将编辑距离计算重新解释为网格中的最短路径，其中一个轴是`S`另一个是当前的子字符串`T`。 每次移动对应于插入、删除或替换，每次成本为 1。我们从不探索成本超过的路径`k`。 

我们处理`T`从左到右，将每个位置视为许多子串的潜在端点。 

1. 对于每个起始索引`l`在`T`，我们初始化一个DP数组`dp`在哪里`dp[j]`表示之间的最小编辑距离`S[0:j]`和空字符串，这只是`j`。 我们立即截断上面的值`k+1`到一个哨兵值，意思是“太大”。 

此初始化反映了在读取任何字符之前`T`，与前缀匹配`S`只需要删除。 

1.我们通过迭代来扩展子串`r`从`l`到`n-1`，更新第二个DP阵列`ndp`基于插入`T[r]`。 

对于每个`i`在`S`，我们计算转换`dp[i]`,`dp[i-1]`， 和`ndp[i-1]`分别对应删除、替换、插入。 这是标准的 Levenshtein 递归，但我们将所有结果限制为`k+1`。 

这样做的原因是子字符串的每个扩展只添加一个字符，因此只添加一个 DP 列。 

1. 计算后`ndp`，我们检查`ndp[m]`在哪里`m = |S|`。 该值是之间的编辑距离`S`和`T[l:r+1]`。 如果它 ≤ k，我们就增加该距离的答案。 

这是有效的，因为每个`(l, r)`对恰好对应于一个子串。 

1. 如果所有值都在`ndp`超过`k`，我们停止扩展这个`l`，由于进一步扩展只能增加或维持距离，切勿因已经超出允许的频带而将其降低到阈值以下。 

这种修剪可以防止实践中出现二次爆炸。 

### 为什么它有效

 DP 状态始终表示仅限于当前子字符串的前缀的正确最小编辑距离，因为每次转换完全对应于一个有效的编辑操作。 钳位值以上`k+1`保留所有 ≤ k 的结果的正确性，因为任何产生 ≤ k 的值的最佳路径从不依赖于高于 k 的中间状态。 因此，丢弃大状态不会影响所需范围内任何可达的最优解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input().strip())
    S = input().strip()
    T = input().strip()

    n, m = len(T), len(S)
    INF = k + 1

    ans = [0] * (k + 1)

    for l in range(n):
        dp = list(range(m + 1))
        dp = [min(x, INF) for x in dp]

        if dp[m] <= k:
            ans[dp[m]] += 1

        for r in range(l, n):
            ndp = [0] * (m + 1)
            ndp[0] = min(dp[0] + 1, INF)

            for i in range(1, m + 1):
                cost_del = dp[i] + 1
                cost_ins = ndp[i - 1] + 1
                cost_sub = dp[i - 1] + (S[i - 1] != T[r])

                ndp[i] = min(cost_del, cost_ins, cost_sub, INF)

            dp = ndp

            if dp[m] <= k:
                ans[dp[m]] += 1

            if min(dp) > k:
                break

    for i in range(k + 1):
        print(ans[i])

if __name__ == "__main__":
    solve()
```该解决方案迭代每个可能的起始索引`T`并逐渐向右扩展子字符串。 DP 阵列`dp`跟踪相对于前缀的编辑距离`S`。 递归直接编码删除、插入和替换成本。 夹钳至`k+1`确保我们只区分有意义的状态达到所需的阈值。 

提前停止条件`min(dp) > k`很关键。 一旦所有部分对齐成本超过`k`，没有进一步的扩展可以恢复较小距离的有效子串，因此继续只会浪费计算。 

## 工作示例

 考虑`S = "a"`和`T = "aab"`， 和`k = 2`。 

我们跟踪从以下位置开始的子串`l = 0`。

 | ---| ---| ---| ---|

 这显示了重复字符如何通过插入逐渐增加编辑距离。 

现在考虑`S = "ab"`和`T = "acb"`。 

| r | 子串| dp[米] | 解读|

 | 0 | “一个”| 1 | 删除或替换 |

 | 2 | “ACB”| 1 | 最佳对准偏移|

 这表明编辑距离不仅取决于局部不匹配，还取决于全局对齐结构。

 ## 边缘情况

 一个重要的边缘情况是当`S`是单个字符并且`T`由重复的相同字符组成。 在这种情况下，每个子字符串都具有纯粹基于长度差异的可预测线性编辑距离，并且 DP 可以正确累积插入而无需替换。 该算法处理这个问题是因为每个扩展`r`增加`dp[m]`当字符不匹配或需要插入时，截断值恰好为 1，并且截断不会干扰值 ≤ k。 

另一个边缘情况是当`k = 0`。 之间仅精确匹配`S`和子串`T`应该算。 DP 简化为精确的子串匹配，并且早期修剪会立即拒绝任何不匹配，实际上表现为滚动精确匹配 DP。 

当出现第三种边缘情况时`|S|`很大但是`T`很小。 DP 正确地初始化删除重状态，算法对删除大部分的子串进行计数`S`成本低，即使长度差异很大也能确保正确性。
