 ## 解决方案
 ## 问题理解

 我们得到一个项目集合，每个项目都有两条信息：一个强制性的“尺寸”值$p_i$，以及可能的奖金值列表$w_{i,1}, w_{i,2}, \dots, w_{i,p_i}$。 玩家选择所有项目的顺序。 当项目按该顺序处理时，我们维护它们的运行前缀和$p_i$价值观。 

当处理一个项目时，当前的前缀总和决定了该项目的多少仍然可以由全局预算“支付”$k$。 如果该项之前的前缀和加上其完整大小不超过$k$，我们可以在等级上充分应用该物品的加成$p_i$。 如果前缀和至少已经是$k$，该项目没有任何贡献。 否则，仅应用部分金额，并且奖金恰好对应于剩余容量，最多可达$k$。 

关键的决定是项目的排列。 不同的订单在每一步都会改变前缀和，这会改变每个项目是否完全贡献、部分贡献或根本不贡献，以及哪个索引$w_{i,j}$被使用。 

任务是最大化收集的奖金总额。 

限制条件$n \le 3000$,$k \le 3000$， 和$p_i \le 10$强烈建议采用动态编程解决方案，该解决方案取决于总处理大小$k$。 尝试所有排列的解决方案是阶乘的并且立即不可行。 甚至$O(n^2 k)$或者$O(nk \log n)$必须小心处理，但可能是可以接受的。 

部分消费会产生微妙的边缘行为：一个项目可能会在边界处被精确地“切割”。$k$，这决定了哪个$w_{i,j}$被使用。 天真的贪婪方法会失败，因为放置大量$p_i$早期或晚期不仅会改变未来的可用性，还会改变哪个指数$w_{i,j}$为每个项目触发。 

例如，考虑$k = 3$和两项：

 - 项目 A：$p=2, w=[0, 10]$- B 项：$p=2, w=[0, 1]$如果我们将 A 放在第一位，它会完全达到 2 级并获得 10，而没有为 B 留下空间。如果我们将 B 放在第一位，A 可能会被部分削减，但仍会获得不同的奖励配置。 最佳排序取决于截断如何与每个项目的奖励曲线相互作用。 

## 方法

 暴力解决方案将枚举所有排列$n$项目并模拟每个订单的扫描过程。 对于每个排列，我们维护一个前缀和，并根据每个项目是否被完全采用、部分采用或忽略来累积贡献。 这是正确的，因为它直接遵循流程的定义。 

然而，有$n!$排列。 即使是为了$n = 12$，这已经超出了任何可行的限制。 每次模拟费用$O(n)$, 给予$O(n \cdot n!)$，这是完全不可行的。 

关键的观察结果是，该过程仅取决于迄今为止消耗的总大小，而不取决于已处理的物品的身份。 一旦我们确定了顺序，在每一步我们只关心当前的总和$s$，并且选择一个项目会发生变化$s$经过$p_i$。 这表明前缀和上有类似背包的 DP。 

我们将问题重新解释为选择一个排序，相当于选择一个增量序列，该序列的总和达到$k$，同时最大化奖励贡献，这取决于每个项目相对于当前总和的放置时间。 自从$p_i \le 10$，每个项目仅稍微改变状态，我们可以围绕累积总大小构建 DP 转换。 

我们根据到目前为止已累积的总大小以及已使用的项目数来定义 DP。 然而，跟踪哪些项目被直接使用的规模太大。 相反，我们利用这样一个事实：每个项目的贡献仅取决于它所在的最终前缀和。 这允许在总消耗能力的状态下以最佳优先的方式转变为处理项目。 

标准解决方案是处理超过背包容量的 DP 中的项目，其中我们决定每个项目相对于不断增长的前缀的调度时间。 各州$dp[s]$表示当前前缀和为时可实现的最大奖励$s$，然后我们尝试接下来放置一个项目。 

放置物品时$i$在状态$s$，我们确定：

 - 如果$s \ge k$,贡献0
 - 如果$s + p_i \le k$, 全额出资$w_{i,p_i}$- 否则部分贡献$w_{i,k-s}$然后我们过渡到状态$s + p_i$，上限为$k$。 

这本质上是分层状态图上的类似最短路径的 DP$0 \to k$，其中每个项目都会引起状态之间的转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 |$O(n! \cdot n)$|$O(n)$| 太慢了|
 | 前缀和上的状态 DP |$O(nk)$|$O(k)$| 已接受 |

 ## 算法演练

 1.初始化一个大小为DP的数组$k+1$， 在哪里$dp[s]$存储处理某些项目并达到累积大小后可获得的最大总奖金$s$。 所有值都以负无穷开始，除了$dp[0] = 0$。 这表示在选择任何项目之前开始。 
2. 以允许将每个项目放置在排序中的任意点的方式逐个迭代项目。 为了实现这一点，对于每个项目，我们按降序对所有状态执行 DP 松弛$s$，防止同一物品多次使用。 
3. 对于每个州$s$，计算下一个状态$s' = \min(k, s + p_i)$。 该模型模拟了放置项目时前缀和如何增加。 
4. 计算奖励贡献取决于$s$。 如果$s \ge k$，贡献为 0，因为缓冲区已耗尽。 
5. 如果$s + p_i \le k$， 添加$w_{i,p_i}$。 这对应于在剩余容量内完全覆盖该项目。 
6. 否则计算剩余容量$r = k - s$并添加$w_{i,r}$，因为该项目在边界处被部分切割。 
7. 更新$dp[s'] = \max(dp[s'], dp[s] + \text{contribution})$。 
8.处理完所有项目后，答案是所有dp状态中的最大值。 

### 为什么它有效

 DP 状态仅对总消耗容量进行编码，这是影响未来项目评估方式的唯一全局量。 每个转换模拟将特定项目放置在排序中的下一个项目。 由于每个排列都对应于某些项目放置序列，并且每个放置都表示为 DP 转换，因此会隐式探索所有有效的排序。 

递减迭代$s$确保每个 DP 层中的每个项目最多使用一次，从而在不显式跟踪项目身份状态的情况下保持正确性。 这保证了每个项目在任何构造的序列中只贡献一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    items = []
    for _ in range(n):
        tmp = list(map(int, input().split()))
        p = tmp[0]
        w = tmp[1:]
        items.append((p, w))

    dp = [-10**18] * (k + 1)
    dp[0] = 0

    for p, w in items:
        ndp = dp[:]
        for s in range(k + 1):
            if dp[s] < 0:
                continue

            if s >= k:
                gain = 0
                ns = k
            else:
                if s + p <= k:
                    gain = w[p - 1]
                else:
                    gain = w[k - s - 1]
                ns = min(k, s + p)

            ndp[ns] = max(ndp[ns], dp[s] + gain)

        dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```DP 数组跟踪每个可能消耗的前缀和的最佳可实现奖励。 该转换严格按照定义仔细地区分全部贡献、部分贡献和零贡献情况。 使用复制数组`ndp`确保每个项目在每个排序层使用一次，而不是在同一迭代中重复链接。 

一个微妙的实现点是索引$w$。 由于Python是从0开始的，$w_{i,j}$被访问为`w[j-1]`。 部分案例使用`k - s - 1`将剩余容量转换为正确的指数。 

## 工作示例

 考虑一个小案例，其中$k = 3$和两项：

 第 1 项：$p=2, w=[5, 9]$第 2 项：$p=1, w=[4]$我们从$dp = [0, -\infty, -\infty, -\infty]$。 

| 步骤| 项目 | s | 增益| ns | dp[s] + 增益 | 更新 dp[ns] |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 项目 1 | 0 | 5 | 2 | 5 | dp[2]=5 |
 | 1 | 项目 1 | 2 | 9 | 3 | 9 | dp[3]=9 | dp[3]=9
 | 2 | 项目 2 | 0 | 4 | 1 | 4 | dp[1]=4 |
 | 2 | 项目 2 | 2 | 0 | 3 | 5 | dp[3]=max(9,5)=9 | dp[3]=max(9,5)=9 |

 最终 dp 显示最佳值为 9。 

该跟踪显示了将项目放置在不同位置如何影响可达状态，并表明 DP 正在通过状态转换有效地探索不同的有效顺序。

 ## 边缘情况

 一个关键的边缘情况是当$k = 0$。 DP 开始于$dp[0]$，但每个项目都会立即落入“已满”类别，并且不会做出任何贡献。 该算法处理这个问题是因为每个转换都会检查$s \ge k$并分配零增益。 

另一种情况是项目的大小提前超过剩余容量。 例如，$k=3$,$p=5$,$w=[2,4,6,8,10]$。 在状态$s=1$，我们计算剩余的$k-s=2$，因此贡献变为$w[2]=6$。 DP 使用部分规则正确限制了贡献。 

最后，考虑多个大型项目争夺早期安置。 DP 自然地处理这个问题，因为每个项目都会在每个状态下进行尝试，因此无论哪种排序产生更好的前缀状态都将通过最大化来主导，而不需要显式的排列推理。
