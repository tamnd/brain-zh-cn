 ## 解决方案
 ## 问题理解

 我们获得了一系列独立的工作。 每项工作都代表一个设计要求，托尼可以接受也可以忽略。 如果他接受了一份工作，则需要一定的时间才能完成，并且必须在严格的截止日期之前完成，否则该工作将被视为无效并且没有任何贡献。 

每项工作都有一个有保证的基本利润，如果在截止日期之前完成，就可以获得该利润。 除此之外，每项工作都可能提供奖金，但奖金并不固定。 相反，它取决于从给定范围中统一选择的两个独立的随机值。 仅当作业在第二个时间阈值之前完成时才会授予奖金，并且可以根据这些范围计算其预期值。 

任务是选择作业的子集以及在一台机器上按顺序执行它们的顺序，以便所有选定的作业都能满足其截止日期，并且预期总利润最大化。 

从调度的角度来看，这是一个子集选择加排序问题。 每项工作都会消耗时间，施加截止日期限制，并贡献与其预期利润相等的权重。 顺序很重要，因为作业的可行性取决于累积的处理时间。 

这些限制允许最多 20 个工作岗位。 这立即排除了任何 n 平方或更高的多项式算法的相关性，因为主要瓶颈不是 n 本身，而是作业的子集。 检查所有子集的解决方案是可行的，因为 2^20 约为一百万，这是穷举搜索的正确比例。 

主要的边缘情况是当作业的子集单独满足截止日期但不存在同时满足所有约束的排序时。 例如，如果一项作业的截止日期很短但处理时间很长，那么稍后放置它可能会破坏可行性，即使它单独看起来是有效的。 当多个作业共享相同的截止日期和处理时间时，会出现另一个微妙的情况； 仅按截止日期进行贪婪排序并不能保证与子集选择相结合时的最优性。 

## 方法

 暴力方法将尝试每个可能的作业子集，并针对每个子集检查是否存在满足所有截止日期同时最大化利润的有效顺序。 对于固定子集，检查可行性已经需要按截止日期对作业进行排序或探索排列，这每个子集至少花费 O(k log k)，如果天真地完成，则可能是 O(k!)。 

作业最多有 20 个，大约有 1,048,576 个子集。 即使每个子集进行一次 O(n) 检查也已经导致大约 2000 万次操作，这是边界但可行的，而任何阶乘或子集大小的指数排序检查都变得不可能。 

关键的观察是，一旦子集固定，满足截止日期的最佳排序始终是按截止日期对作业进行排序。 这将可行性检查转变为单个确定性扫描。 然后，问题就纯粹是选择一个子集，其按截止日期排序的时间表有效且其总预期利润最大化。 

因此，结构是：枚举子集，计算其预期利润，按截止日期对所选作业进行排序，并验证累积处理时间不会超过截止日期。 这将问题从调度优化简化为可行性检查的子集 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个子集的强力排列 | O(2^n · n!) | O(2^n · n!) | O(n) | 太慢了 |
 | 贪婪排序的子集枚举 | O(2^n · n log n) | O(2^n · n log n) | O(n) | 已接受 |

 ## 算法演练

1. 预先计算每项工作的奖金预期值。 由于奖励在矩形上是均匀随机的，因此如果模型是乘法模型，则其期望值只是两个范围的中点相乘；如果模型是乘法模型，则其期望值是相加的总和（如独立性所暗示的那样）。 这将每项工作转换为确定的利润值。 
2. 对于每个工作子集，将其总利润计算为基本利润和预期奖金之和。 这定义了该子集的目标值，与排序无关。 
3. 提取子集中的作业并按截止日期以非降序对它们进行排序。 选择这种顺序是因为任何能够满足所有截止日期的计划都必须首先与最早的截止日期一致； 否则，截止日期较早的工作可能会被较晚的工作不必要地延迟。 
4. 按此排序顺序模拟执行，维护运行时间计数器。 对于每个作业，添加其处理时间并立即检查累计时间是否超过其截止时间。 如果是，则完全丢弃该子集。 
5. 如果子集可行，则将其利润与当前最佳答案进行比较并更新。 

按截止日期排序正确的原因是，任何可行的计划都可以转换为按非递减截止日期对作业进行排序的计划，而不会增加任何完成时间违规。 如果较晚截止日期的作业出现在较早截止日期的作业之前，则交换它们不会降低可行性，因为较早截止日期的作业只会因较早的截止日期而受益。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    jobs = []
    
    for _ in range(n):
        d, p, c, lx, rx, ly, ry = map(int, input().split())
        # expected bonus: E[x] * E[y] since independent uniform variables
        ex = (lx + rx) / 2.0
        ey = (ly + ry) / 2.0
        bonus = ex * ey
        jobs.append((d, p + bonus, c))
    
    ans = 0.0
    
    for mask in range(1 << n):
        total = 0.0
        subset = []
        
        for i in range(n):
            if mask & (1 << i):
                d, val, c = jobs[i]
                total += val
                subset.append((d, c))
        
        subset.sort()
        
        t = 0
        ok = True
        for d, c in subset:
            t += c
            if t > d:
                ok = False
                break
        
        if ok:
            ans = max(ans, total)
    
    print(f"{ans:.10f}")

def main():
    solve()

if __name__ == "__main__":
    main()
```该实现直接反映了算法。 通过计算其预期奖金，将每项工作预处理为确定性权重。 子集循环使用位掩码枚举所有组合，这对于 n 最多 20 来说足够有效。 

在每个子集中，我们构建一个仅包含截止日期和处理时间的简化列表。 对该列表进行排序会强制执行可行性检查的贪婪最优排序。 运行时间检查是增量完成的，确保我们尽早发现违规行为。 

一个微妙的细节是对期望值使用浮点运算。 由于所需的精度是 1e-6，双精度就足够了。 累加一致地使用浮点以避免混合整数和浮点比较。 

## 工作示例

 考虑一个具有两个作业的小型实例，两个作业都可以安排。

 | ---| ---| ---| ---| ---| ---|
 | 1 | {} | {} | 0 | 是的 | 0 |
 | 2 | {1} | (1) | 5 → 好的 | 是的 | 10 | 10

现在考虑一个排序很重要的情况。 

| 步骤| 子集| 按截止日期排序| 时间进程 | 可行| 利润|
 | ---| ---| ---| ---| ---| ---|
 | 1 | {A，B} | A(3)、B(5) | 4 → 7（失败）| 没有| - |

这说明了为什么子集选择不能与可行性检查分开。

 ## 边缘情况

 当子集有利可图但仅由于排序而变得不可行时，就会出现极端情况。 如果两项工作的截止日期非常接近且处理时间相似，则交换它们可能会决定可行性。 按截止日期排序可确保始终先处理较早的截止日期，从而防止隐藏的违规行为。 

另一种情况是所有工作都有相同的截止日期。 该算法简化为检查前缀的总处理时间是否保持在该共享限制内。 子集枚举仍然有效，排序变得无关紧要但无害。 

最后一个微妙的情况是预期奖金主导基本利润。 由于预期值是小数，因此浮点累加必须在子集中保持一致。 使用双精度可确保在所需公差下的稳定性。
