 ## 解决方案
 ## 问题理解

 我们有一排盒子，每个盒子都有固定的容量。 除此之外，还有一个数字代表 Elisa 想要在一个盒子中放置多少相同的工件。 任务是选择一个可以同时容纳所有物品的盒子，这意味着它的容量必须至少达到所需的数量。 如果多个框满足此条件，则所选框必须是该行中最早的框。 如果没有足够大的盒子，答案就是不存在有效的选择。 

输入本质上是容量列表加上阈值。 输出是指向不小于阈值的第一个容量的单个索引。 

限制最多允许十万个盒子，而且容量也可以很大。 这立即排除了任何二次方，例如检查所有对或每个查询重复扫描段。 单次线性传递已经在限制范围内，因为在典型的时间限制下，超过十万个元素的一次传递可以忽略不计。 

微妙的失败案例主要与正确性有关，而不是与性能有关。 一个常见的错误是返回任何有效索引而不是最小的索引。 例如，如果容量是`5 1 10 7`要求是`6`，索引 3 和 4 都可以工作，但必须选择索引 3。 另一个错误是忘记了没有盒子工作的情况，例如容量`1 2 3`有要求`10`，其中正确的输出是`-1`而不是像这样的无效索引`0`或者`N`。 

## 方法

 蛮力方法很简单。 我们扫描每个盒子并检查其容量是否至少达到要求的数量。 我们跟踪所有有效的索引，或者只记住第一个有效的索引。 这是正确的，因为它直接遵循答案的定义。 其成本是每个框进行一次比较，从而导致 O(N) 操作，这对于给定的限制已经足够有效。 

不需要更复杂的优化技术，如二分搜索或前缀预处理，因为只有一个查询，并且没有超出单个线性顺序的结构。 唯一有意义的优化是在找到第一个有效框后尽早停止，因为后来的候选者无法改进答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力扫描 | O(N) | O(1) | O(1) | 已接受 |
 | 提前停止扫描 | O(N) 最坏情况，O(k) 最好情况 | O(1) | O(1) | 已接受 |

 关键的观察是，仅在扫描方面，索引顺序的要求是单调的，而不是值顺序，因此排序或高级数据结构只会破坏原始索引要求。 

## 算法演练

 1.读取箱子数量和所需容量值。 
2. 按给定顺序读取容量列表。 
3. 从左到右遍历列表，检查每个容量是否符合要求。 
4. 一旦发现容量至少达到所需值，则输出其索引并终止。 
5.如果遍历结束没有找到有效框，则输出`-1`。 

在第一个有效框处立即停止的原因是，当我们向右移动时，索引会增加，并且问题明确地倾向于所有有效选择中最小的索引。 

### 为什么它有效

 正确性依赖于这样一个事实：答案纯粹由每个索引上的谓词独立定义：一个框是否有效仅取决于其容量。 盒子之间没有交互，没有积累，也不依赖于先前选择的元素。 由于这种独立性，从左到右扫描可确保第一次满足条件时，我们已经达到了满足条件的最小可能索引。 后来的决定无法用更好的候选者来取代它，因为任何后来的索引都更大。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    for i, val in enumerate(a, 1):
        if val >= m:
            print(i)
            return
    print(-1)

if __name__ == "__main__":
    solve()
```该解决方案以线性时间读取输入并立即扫描列表。 枚举从 1 开始，因为输出是基于 1 的索引。 提前返回可确保我们在找到最佳答案后不会继续扫描，尽管即使没有最佳答案，复杂性仍将保持线性。 

一个常见的实施错误是忘记从 1 开始的索引要求，这会将每个答案移动 1。 另一种是使用严格比较`>`而不是`>=`，它会错误地拒绝容量完全符合要求的盒子。

 ## 边缘情况

 一个边缘情况是第一个框已经满足要求。 该算法通过立即返回索引 1 而不进一步扫描来处理它，因为第一次比较成功并触发终止。 

另一种情况是没有盒子满足要求。 循环完全完成并且函数回退到返回`-1`，正确地表明没有解决方案。 对于像这样的输入`3 10`有能力`1 2 3`，每次比较都失败，因此不会发生提前返回，最终输出为`-1`。 

第三种情况是多个盒子满足要求时。 为了`5 5`有能力`5 7 6 5`，算法返回索引 1，因为这是条件第一次变为 true。 后来的有效框不再被考虑，这符合选择最小索引的要求。
