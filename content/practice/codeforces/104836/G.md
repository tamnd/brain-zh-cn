 ## 解决方案
 ## 问题理解

 我们有一组固定的基地$p_i$和相关权重$c_i$。 每个查询给出一个短数字字符串$s$，并且我们可以将其分成几个连续的部分。 每个部分必须是不带前导零的有效十进制数。 

对于每个细分市场$t$，我们尝试将其解释为给定基数之一的完美幂：必须存在一个索引$i$和指数$x \ge 1$这样$t = p_i^x$。 如果可能的话，该细分市场将贡献价值$c_i \cdot x$，否则贡献为零。 分区的质量是其所有分段中贡献最小的。 任务是在所有可能的分区上最大化这个最小值，并计算有多少分区达到了这个最佳值。 

关键的难点在于字符串长度最多为18，因此每次查询都很小，但是碱基和查询的数量却很大。 这将解决方案推向对基集和每字符串动态编程进行大量预处理的方向。 

一种幼稚的方法会尝试所有方法来分割字符串，该字符串的长度已经是指数级的。 对于每个片段，它还会尝试检查它是否是某些片段的幂$p_i$，这又增加了一层成本。 尽管 18 很小，但如果在没有结构的情况下独立执行每个查询，指数分区和昂贵的检查的组合就会变得太慢。 

还有一种微妙的边缘情况，涉及具有多种幂表示形式的数字。 例如，像这样的值$64$可能是$2^6$或者$4^3$或者$8^2$。 如果我们不预先计算所有有效的表示，我们可能会错过依赖于选择不同的基数-指数对的最佳分割。 

另一个棘手的情况来自前导零。 像“01”这样的段决不能被视为有效，即使在数字上它等于 1。任何过早将子字符串转换为整数并进行数字比较的方法都将错误地接受这种情况。 

最后，由于我们最大化了分段的最小值，贪婪的选择会失败。 局部强分割可能会迫使稍后出现弱分割并降低全局分数。 

## 方法

 强力解决方案将枚举将长度最多为 18 的字符串拆分的所有可能方法。拆分次数为$2^{17}$，约130k。 对于每个分区，我们检查每个段，并且对于每个段，我们测试它是否等于$p_i^x$对于任何$i$和$x$。 即使使用预计算，这也会变得昂贵，因为每个段的多个基数上的子串幂检查会导致所有分区和查询上乘以一个大的常数因子。 

关键的结构观察是字符串长度很小，因此我们可以将每个子字符串视为候选段，并在每次查询时预先计算其“值”。 对于每个子串，我们需要知道可实现的最佳值$c_i \cdot x$使得它等于$p_i^x$。 自从$s$很短，我们可以枚举所有子字符串并将它们与预先计算的幂值进行匹配。 

一旦每个子串都有一个权重，问题就变成了一个经典的分区DP：我们希望将前缀分割成多个片段，以最大化最小片段权重，并计算有多少种方法可以实现最佳最小值。 这本质上是间隔内的最大最小 DP，并结合保留最佳瓶颈的计数路径。 

转换很简单：在前缀上进行 dp，尝试所有先前的剪切位置，并传播最小分数。 唯一重要的部分是当多个转换产生相同的最佳值时正确处理计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n \cdot n \cdot n)$|$O(1)$| 太慢了 |
 | 预计算 + 子串上的 DP |$O(n^2 \cdot q + \text{precompute})$|$O(n^2)$| 已接受 |

 ## 算法演练

 我们将解决方案分为两个阶段：预处理基本集和回答每个查询字符串。 

1. 对于每对$(p_i, c_i)$，产生所有的力量$p_i^x$适合 18 位数字。 对于每个生成的数字，存储最佳值$c_i \cdot x$。 这将创建一个字典，将数字字符串映射到其可实现的最佳美感。 生成幂而不是稍后检查子串的原因是求幂模式是稀疏的，而子串是密集的。 
2. 对于每个查询字符串$s$, 枚举所有子串$s[l:r]$。 对于每个子串，如果它没有前导零并且出现在预先计算的映射中，则为其分配等于存储的美度的权重； 否则分配零。 这一步将问题转化为加权分割问题。 
3. 定义一个DP，其中$dp[i]$存储一对$(best\_value, ways)$对于前缀$s[0:i]$。 最佳值是最大可实现的最小段权重，并计算有多少个分区实现它。 
4. 初始化$dp[0] = (+\infty, 1)$，因为空前缀没有限制段。 
5. 对于每个位置$i$，迭代所有先前的剪切位置$j < i$。 考虑细分市场$s[j:i]$和它的重量$w$。 将其与$dp[j]$通过采取$min(dp[j].best, w)$。 这会产生一个候选分数$dp[i]$。 我们跟踪这些候选人中的最大值，并总结出平局的方法。 
6. 当多个转换产生相同的最小值时，我们将它们的计数相加。 当转换提高最佳值时，我们会覆盖计数。 
7. 每个查询的最终答案是$dp[n]$。 

正确性依赖于这样一个事实：任何最佳分区完全由其最后一次切割决定。 每个前缀状态都已经聚合了所有最佳方式，因此用一个段扩展它可以保留最佳子结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import defaultdict

# Precompute all valid powers up to 18 digits
pow_map = {}

def limit_len(x):
    return len(str(x)) <= 18

# build power dictionary
# store best c_i * x per numeric value as string
n = int(input())
bases = []

for _ in range(n):
    p, c = input().split()
    p = int(p)
    c = int(c)

    cur = p
    exp = 1
    while cur <= 10**18:
        s = str(cur)
        if len(s) > 18:
            break
        if s not in pow_map or pow_map[s] < c * exp:
            pow_map[s] = c * exp

        if cur > 10**18 // p:
            break
        cur *= p
        exp += 1

q = int(input())

INF = 10**30

for _ in range(q):
    s = input().strip()
    m = len(s)

    # compute substring weights
    w = [[0] * m for _ in range(m)]

    for i in range(m):
        if s[i] == '0':
            continue
        val = 0
        for j in range(i, m):
            val = val * 10 + (ord(s[j]) - 48)
            if j - i + 1 > 18:
                break
            key = str(val)
            if key in pow_map:
                w[i][j] = pow_map[key]

    dp_val = [-1] * (m + 1)
    dp_cnt = [0] * (m + 1)

    dp_val[0] = 10**30
    dp_cnt[0] = 1

    for i in range(1, m + 1):
        best = -1
        cnt = 0
        for j in range(i):
            if dp_val[j] < 0:
                continue
            cur = min(dp_val[j], w[j][i - 1])
            if cur > best:
                best = cur
                cnt = dp_cnt[j]
            elif cur == best:
                cnt += dp_cnt[j]
        dp_val[i] = best
        dp_cnt[i] = cnt

    print(dp_val[m], dp_cnt[m])
```预处理步骤构建从数字字符串到所有基数指数表示中可达到的最佳得分的映射。 这避免了重新计算每个子字符串的指数检查。 

对于每个查询，我们增量地预先计算所有子字符串值。 长度 18 处的早期中断至关重要，因为较长的子串无法匹配任何有效幂。 通过跳过开始位置强制执行前导零处理`s[i] == '0'`。 

然后 DP 将每个子串视为潜在的片段权重。 这`dp_val`数组存储最佳可实现的最小值，并且`dp_cnt`跟踪有多少种方法可以实现它。 初始化集`dp_val[0]`到一个非常大的值，因此第一段不会人为地降低最小值。 

一个微妙的点是，必须仅对达到相同最佳分数的转换进行计数； 否则我们要么计算过多，要么失去有效的分解。

 ### 示例 1

 输入字符串：`"36"`子串权重：

 “3”→ 2、“6”→ 1、“36”→ 2

 DP 转换：

 | 我| j | 段 | w[j:i] | dp[j] | dp[j] | 分钟 | 迄今为止最好的|
 | ---| ---| ---| ---| ---| ---| ---|

 最终答案：分割“3”+“6”的最佳最小值为 1，分割“36”的最小值为 2。 由于我们最大化最小值，结果是 2 和 1 路。 

这显示了单段分区如何在分割较少的情况下占据主导地位。

 ## 边缘情况

 临界边缘情况是当子串在数值上等于幂但具有前导零时，例如`"09"`。 该算法显式地跳过此类开始，因此它永远不会进入子串映射，从而防止无效的高分片段。 

另一种情况是重叠的权力表示，例如`"64"`，这两者都可以是$2^6$和$4^3$。 预处理存储最大$c_i \cdot x$，因此无论代表性如何，DP 总是会看到最好的贡献。 

最后一种情况是根本没有有效段的字符串。 然后所有子串权重都为零，DP 仍然正确运行并返回零，其计数等于所有可能的分区，因为每个分割都有相同的最小值零。
