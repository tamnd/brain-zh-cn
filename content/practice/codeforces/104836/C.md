 ## 解决方案
 ## 问题理解

 我们有两部电影专营权，每部都有多个放映开始时间。 每次放映都有固定的持续时间，因此每个开始时间都隐式定义了时间轴上的完整间隔。 有效的计划包括选择第一部电影的放映和第二电影的放映，这样两个选定的间隔在时间上不会重叠，这意味着一个必须严格在另一个开始之前完成。 

一旦选择了有效的一对，我们就会测量从早期筛选开始到后期筛选结束的总时间跨度。 目标是选择两场不重叠的放映，每部电影放映一场，从而最大限度地减少总跨度。 

每部电影的输入大小高达 200,000 次放映。 这立即排除了任何检查所有筛选对的解决方案，因为这在最坏的情况下需要多达 4e10 次比较，这远远超出了可行的限制。 我们需要利用时间表中的顺序和结构。 

一个微妙的点是同一部电影中的放映可能会任意重叠。 这意味着我们不能假设一个列表内不相交的间隔，因此任何仅基于一个列表内的局部排序的贪婪假设都是不安全的。 

一些可能会阻碍简单解决方案的边缘情况：

 如果一部电影只有一次放映，那么答案就简化为从其他列表中选择最兼容的放映。 例如，如果第二部电影的所有放映都发生得很早，则唯一有效的顺序可能是第二部电影然后是第一部电影。 

如果最佳解决方案需要从一个列表中选择最晚的可能开始，并从另一个列表中选择最早的兼容开始，则天真的“最近开始时间”启发式会失败，因为它忽略了间隔重叠约束。 

## 方法

 蛮力方法很简单：将每次放映解释为一个间隔，然后尝试由每部电影的一个间隔组成的所有对。 对于每一对，检查两个可能的顺序，确定它们是否不重叠，并计算结果跨度。 这是有效的，因为它明确地评估每一个有效的组合，所以它不会错过最佳的组合。 

但是，如果一部电影放映 n 次，另一部电影放映 m 次，则此方法执行 O(nm) 检查。 当两者都达到 2e5 时，这将变成 4e10 操作，这太慢了。 

关键的观察是，一旦排序固定，目标的结构仅取决于区间的极端端点。 如果我们修复第一部电影的一个放映，我们只需要第二部电影的最佳兼容放映。 兼容性降低到开始时间的阈值条件，因为每个间隔都是由其开始时间加上固定持续时间确定的。 

因此，我们可以预处理一个列表，而不是对所有内容进行配对，以便对于任何给定的时间阈值，我们可以使用二分搜索快速找到另一个列表中的最佳候选者。 我们将二维配对问题简化为扫描一个数组并在对数时间内查询另一个数组。 

这会导致 O(n log m + m log n) 解决方案或 O((n + m) log (n + m))，具体取决于实现。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了|
 | 最佳 | O(n log n + m log m) | O(n log n + m log m) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将每次筛选视为一个间隔。 从 b_i 开始的 Borbi 筛选在 b_i + t_b 结束，从 o_j 开始的 Oпергеймер 筛选在 o_j + t_o 结束。 

我们想要考虑两种可能的顺序，因此我们计算 Borbi 为第一、Oпергеймер 为第二时的最佳答案，然后交换角色。 

### 1. 隐式预先计算结束时间

 我们不明确存储间隔； 相反，我们依赖于开始数组并动态计算结束时间。 这使内存保持简单并避免不必要的结构。

### 2. 对两个数组进行排序

 尽管输入已按开始时间排序，但如果约束发生变化或输入保证较弱，排序仍可确保正确性。 更重要的是，它允许二分搜索推理有效。 

### 3. 为第二部电影构建一个助手

 对于固定顺序，先说 Borbi，然后说 Oпергеймер，我们希望对于每个 Borbi 间隔，最早的 Oпергеймер 间隔在 Borbi 结束后开始。 

为此，我们在 Oпергеймер 开始数组中二分搜索第一个索引 j，使得 o_j >= b_i + t_b。 

一旦我们找到这样的 j，该间隔就是第一部电影放映的最早有效的第二部电影选择。 任何较晚的启动只会增加总跨度，因此最早的可行启动始终是最佳的。 

### 4. 计算该方向的候选答案

 对于每个我：

 我们计算跨度 = (o_j + t_o) - b_i。 

我们跟踪所有有效 i 的最小值。 

### 5. 角色互换重复

 现在我们首先假设 Oпергеймер，然后假设 Borbi，并对称地重复相同的过程。 

最终答案是两个方向上的最小值。 

### 为什么它有效

 核心不变量是，对于固定的第一次筛选，最佳的第二次筛选始终是第一次筛选结束后最早开始的筛选。 任何后来的候选者都只会增加右端点，同时保持左端点固定或更糟，因此它无法提高跨度。 这将搜索空间从所有兼容间隔减少到每个起始间隔一个二分搜索结果。 由于我们评估了两种可能的排序，因此我们以最佳形式一次性覆盖所有有效的非重叠对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_direction(a_start, a_dur, b_start, b_dur):
    n = len(a_start)
    m = len(b_start)

    ans = float('inf')

    for i in range(n):
        a_l = a_start[i]
        a_r = a_l + a_dur

        # binary search first b_start[j] >= a_r
        lo, hi = 0, m
        while lo < hi:
            mid = (lo + hi) // 2
            if b_start[mid] < a_r:
                lo = mid + 1
            else:
                hi = mid

        j = lo
        if j < m:
            span = (b_start[j] + b_dur) - a_l
            if span < ans:
                ans = span

    return ans

def solve():
    tb, to = map(int, input().split())

    n = int(input())
    b = list(map(int, input().split()))

    m = int(input())
    o = list(map(int, input().split()))

    # Borbi then Oppenheimer
    ans1 = solve_direction(b, tb, o, to)
    # Oppenheimer then Borbi
    ans2 = solve_direction(o, to, b, tb)

    print(min(ans1, ans2))

if __name__ == "__main__":
    solve()
```该解决方案是围绕单向例程构建的。 对于第一个列表中的每个放映，我们计算其结束时间并通过二分搜索找到第二个列表中最早的兼容放映。 二分搜索确保我们只考虑有效的非重叠对。 

一个常见的实现陷阱是忘记严格不重叠意味着第二个起点必须至少等于第一个终点，而不是严格大于。 二分查找中的条件使用`< a_r`，它正确地执行了严格的分离。 

另一个微妙的问题是对称性。 如果我们只检查 Borbi-first，我们会错过最佳排序是 Oпергеймер-first 的情况，因此我们明确评估两个方向。

 ## 边缘情况

 一种关键的边缘情况是只有一种订购才能产生可行性。 例如，如果所有 Oпергеймер 放映都提前结束，而 Borbi 放映较晚开始，则只有 Oпергеймер 优先有效。 该算法处理这个问题是因为相反方向的二分搜索仍然只在可能的情况下找到有效的候选者，而另一个方向只是产生无穷大。 

另一个边缘情况是多个放映同时开始。 由于我们总是通过二分搜索选择最早可行的第二次筛选，因此重复项不会影响正确性。 

最后，当通过最新的可能的第一次筛选确定最佳对时，对所有 i 的扫描保证我们不会错过它，因为每个候选开始都是用其自己的最佳匹配独立评估的。
