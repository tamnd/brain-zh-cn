 ## 解决方案
 ## 问题理解

 我们从一堆糖果开始，想要了解应该邀请多少朋友，以便在经过非常具体的分发过程后，剩下固定数量的糖果。 

分布规律是循环的。 如果有$m$朋友们，糖果按照从朋友1到朋友的顺序一一分发$m$，然后再次从 1 开始重复循环，只要有足够的糖果可以继续给出完整的步骤。 当少于$m$剩下的糖果，该过程停止并保留剩余的糖果。 

所以行为相当于反复做减法$m$将糖果分成块数，然后将剩余的一块一块地分配。 在完成所有大小周期之后$m$，剩下的正是除法的余数$n$经过$m$。 因此最后剩下的就是$n \bmod m$。 

任务是选择$m$使得这个余数等于$k$。 如果没有这样的$m$存在，我们必须报告这是不可能的。 

约束条件$n > k$确保我们不会处理所需余数等于或大于起始量的退化情况，但它仍然留下较大的值$10^{18}$，这排除了尝试所有可能的任何方法$m$值高达$n$。 

一种天真的方法会测试每一个$m$从 1 到$n$, 计算$n \bmod m$，并检查它是否等于$k$。 这对于大输入来说是立即不可行的，因为$n$可以是$10^{18}$，意思是直到$10^{18}$迭代。 

当假设任何除数时，就会出现粗心推理的微妙失败案例$n-k$是可以接受的。 例如，如果$n=30$和$k=4$， 然后$n-k=26$，其除数包括 2 和 13。两者都满足代数条件，但并非全部都有效，具体取决于余数必须严格小于的约束$m$。 如果$m \le k$，余数条件不能成立，因为$n \bmod m$总是小于$m$，所以它永远不能等于$k$如果$m \le k$。 

## 方法

 蛮力的想法很简单。 尝试尽可能多的朋友$m$，模拟分布或直接计算$n \bmod m$，并检查它是否等于$k$。 这是有效的，因为流程定义完全简化为模块化算术。 然而，这需要迭代所有$m$最多$n$，在最坏的情况下是$10^{18}$作业无法及时完成。 

关键的观察是以代数形式重写条件。 如果最后的余数是$k$，则存在一个整数商$q$这样：$$n = q \cdot m + k$$重新排列给出：$$n - k = q \cdot m$$这意味着$m$必须是除数$d = n - k$。 所以不要搜索所有$m$，我们只需要搜索$d$。 在这些除数中，我们必须确保$n \bmod m = k$，这相当于要求$m > k$。 

这将问题转化为寻找最小除数$n-k$严格大于$k$。 除数结构允许我们枚举候选者$O(\sqrt{n-k})$，这对于$10^{18}$限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n)$|$O(1)$| 太慢了|
 | 除数枚举 |$O(\sqrt{n-k})$|$O(1)$| 已接受 |

 ## 算法演练

 1. 计算$d = n - k$。 该数量表示在整个周期中有效均匀分配的糖果数量。 
2.如果$d \le 0$，没有有效的方法来形成正数的完整循环，同时保留余数$k$，所以答案是不可能的。 在这个问题中$n > k$， 所以$d$总是积极的。 
3. 迭代所有整数$i$从 1 到$\lfloor \sqrt{d} \rfloor$。 每个$i$是一个潜在的除数候选者。 
4. 每当$i$划分$d$，同时考虑$i$和$d / i$作为候选值$m$。 这在一次检查中捕获除数对的两个成员。 
5. 对于每个候选除数$m$，检查是否$m > k$。 这个条件保证了余数$k$在模算术约束下有效。 
6. 跟踪最小的有效值$m$枚举过程中遇到的。 我们取最小值，因为任何有效除数都是可接受的，但我们想要确定性的输出。 
7. 检查所有除数后，输出最小的有效除数$m$如果存在，否则输出$-1$。 

### 为什么它有效

 该过程总是简化为等式$n = q \cdot m + k$，这迫使$m$划分$n-k$。 每个有效答案必须显示为除数$n-k$，因此迭代所有除数时搜索空间已完成。 约束条件$m > k$确保余数条件与模算术界限一致。 由于检查了每个有效的候选者并选择了最小值，因此不会错过任何有效的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    d = n - k

    ans = None

    i = 1
    while i * i <= d:
        if d % i == 0:
            j = d // i

            if i > k:
                if ans is None or i < ans:
                    ans = i

            if j > k:
                if ans is None or j < ans:
                    ans = j

        i += 1

    print(ans if ans is not None else -1)

if __name__ == "__main__":
    solve()
```该解决方案将问题简化为除数枚举$d = n - k$。 循环结束$i \cdot i \le d$确保每个除数对只处理一次，即使对于接近的值也能保持运行时高效$10^{18}$。 

仔细的部分是检查两者$i$和$d / i$，因为缺少该对的一侧会忽略有效答案。 第二个关键细节是执行$m > k$，它直接编码模运算中的余数必须小于除数的约束。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(\sqrt{n-k})$| 每个到平方根的潜在除数都会检查一次，每次检查最多产生两个候选 |
 | 空间|$O(1)$| 仅存储恒定数量的变量 |

 平方根复杂度足以满足高达$10^{18}$， 自从$\sqrt{10^{18}} = 10^9$，并且循环仅运行内部最少操作的整数步。

 ## 边缘情况

 当差异出现时，就会出现一种重要的边缘情况$n-k$没有除数大于$k$。 例如，如果$n=100$和$k=99$， 然后$d=1$。 它唯一的除数是 1，不大于 99，所以没有有效的除数$m$存在并且正确的输出是$-1$。 

另一种情况是当$k=0$。 然后我们寻找除数$n$这是严格正数，最小有效除数就是$n$。 该算法自然地处理这个问题，因为$n$被视为候选者，并且 1 如果存在则有效。 

最后一个微妙之处是确保除数对的两个成员都被检查。 如果只是$i$被认为是并且$d/i$被忽略，像这样的情况$d=26$当仅迭代到时会错过正确答案 13$\sqrt{d}$无需配对。
