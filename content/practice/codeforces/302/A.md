 ## 解决方案
 ## 问题理解

 我们得到一个仅包含`1`和`-1`。 对于每个查询`[l, r]`，我们从索引中查看子数组`l`到`r`。 我们可以以任意顺序重新排列该子数组内的元素，并且必须确定该子数组的总和是否有可能为零。 

数字的顺序实际上对于总和并不重要。 重新排列只改变位置，不改变数量`1`沙`-1`存在。 真正的问题是所选的段是否包含相同数量的`1`沙`-1`s。 

如果子数组有长度`k`，然后求和`0`意味着正好有一半的元素是`1`另一半是`-1`。 这立即告诉我们两件事。 首先，线段长度必须是偶数。 二、数量`1`s 必须等于`-1`s。 

约束足够大，我们无法逐个元素地检查每个查询。 两个都`n`和`m`可以达到`2 * 10^5`。 对每个查询进行简单扫描将花费`O(length of segment)`时间，大致变成`4 * 10^10`最坏情况下的操作。 这远远超出了 1 秒的时间限制。 

一些边缘情况很容易处理不当。 

考虑奇数长度的段：```
3 1
1 -1 1
1 3
```正确答案是：```
0
```即使计数很接近，奇数长度的段也永远无法均匀地分成相等数量的段`1`和`-1`。 

另一个微妙的情况是长度均匀但计数不平衡的段：```
4 1
1 1 -1 -1
1 2
```该段`[1, 2]`包含两个`1`s 和没有`-1`s。 重新排列没有任何改变，所以答案仍然是`0`。 

粗心的实现还可能通过尝试模拟重新排列而使问题变得过于复杂。 例如：```
4 1
1 -1 1 -1
1 4
```金额已经是`0`，所以答案是`1`。 不需要实际的重新排列逻辑。 

## 方法

 暴力方法独立处理每个查询。 对于每个段`[l, r]`，我们数一下有多少个`1`沙`-1`出现。 如果计数匹配，我们打印`1`; 否则我们打印`0`。 

这是有效的，因为实现总和的条件`0`正计数和负计数之间完全相等。 问题是速度。 在最坏的情况下，每个查询可能会扫描几乎整个数组。 和`2 * 10^5`查询和`2 * 10^5`元素，总功变成二次方。 

关键的观察是实际值仅`1`和`-1`。 一个段可以有总和`0`当且仅当它的长度是偶数且个数`1`s 等于数量`-1`s。 我们不必每次都单独计算这两个类别，而是可以在全局范围内只计算一个类别。 

假设我们预先计算了总数`1`s 在整个数组中。 让：```
ones = number of elements equal to 1
minus = number of elements equal to -1
```对于长度的查询段`len`：```
len = r - l + 1
```为了使总和为零，我们需要：```
len / 2 <= ones
len / 2 <= minus
```为什么？ 因为该段必须准确包含`len / 2`每个值的副本。 由于重新排列不受限制，因此只有可用性才重要。 

这将每个查询减少为恒定时间检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n + m) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取数组并统计有多少个元素等于`1`。 
2. 计算有多少个元素等于`-1`。 
3. 对于每个查询，计算段长度：```
len = r - l + 1
```4. 如果长度为奇数，则打印`0`。 

零和需要相同数量的`1`和`-1`，这对于奇数个元素来说是不可能的。 
5. 否则，计算：```
need = len // 2
```这是多少`1`沙`-1`s 该段必须包含。 
6. 如果两个全局计数都满足：```
ones >= need
minus >= need
```打印`1`。 否则打印`0`。 

这样做的原因是重新排列消除了所有位置限制。 我们只关心每个值是否存在足够的副本来填充所需大小的段。 

### 为什么它有效

 一段长度`len`有总和`0`恰好当它包含相同数量的`1`沙`-1`s。 因为每个元素要么是`1`或者`-1`，相等的计数意味着：```
count(1) = count(-1) = len / 2
```如果`len`奇怪的是，这不可能立即发生。 

如果`len`是偶数，那么剩下的唯一问题是数组是否至少包含`len / 2`每个值的副本。 因为允许自由地重新排列，所以位置根本不重要。 该算法准确地检查这些必要和充分条件，因此每个答案都是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    arr = list(map(int, input().split()))

    ones = arr.count(1)
    minus = n - ones

    ans = []

    for _ in range(m):
        l, r = map(int, input().split())

        length = r - l + 1

        if length % 2 == 1:
            ans.append("0")
            continue

        need = length // 2

        if ones >= need and minus >= need:
            ans.append("1")
        else:
            ans.append("0")

    print("\n".join(ans))

solve()
```第一部分计算有多少个`1`全球范围内都存在。 由于所有其他值都必须是`-1`，负数的数量很简单`n - ones`。 

每个查询仅取决于段长度。 实际职位`l`和`r`除了确定该长度之外，其他无关紧要。 这是问题的核心简化。 

奇数长度检查首先出现，因为它立即拒绝不可能的情况。 在那之后，`need = length // 2`表示每个值所需的数量。 

一个常见的错误是尝试分析确切的子数组内容。 该语句允许重新排列所选范围内的任何元素，因此只有计数很重要。 

另一个容易出现的差一错误是错误地计算了长度。 由于两个端点都包含在内，因此正确的公式是：```
r - l + 1
```## 工作示例

 ## 边缘情况

 考虑奇数长度的情况：```
3 1
1 -1 1
1 3
```该算法计算：```
length = 3
```由于长度是奇数，因此立即打印`0`。 总和为零需要`1.5`每个值的副本，这是不可能的。 

现在考虑负数不足的偶数段：```
4 1
1 1 1 -1
1 4
```该算法计算：```
length = 4
need = 2
ones = 3
minus = 1
```有足够的`1`但还不够`-1`是。 条件失败，因此输出为：```
0
```这是正确的，因为长度为零的段`4`每个值必须恰好包含两个。 

最后，考虑一个平衡的情况：```
6 1
1 1 -1 -1 1 -1
2 5
```段长度为`4`， 所以：```
need = 2
```全球计数为：```
ones = 3
minus = 3
```两个条件都成功，因此算法打印`1`。 

即使查询的间隔本身可能还没有为零，重新排列允许我们放置两个`1`和两个`-1`s 位于段内，从而达到所需的总和。
