 ## 解决方案
 ## 问题理解

 该问题模拟了岛屿之间的航行。 每个岛屿在 2D 平面上都有一个位置和许多补给品。 出发岛是第一个，目的地是最后一个。 琪亚娜的船的初始行驶能力等于起始岛上已使用的补给量。 每当她到达另一个岛屿时，她都会收集岛上的补给品，从而增加她单次旅行的最大距离。 

任务是确定是否存在一系列岛屿可以让她最终到达目的地。 移动并不局限于岛屿之间已经绘制的路径。 只要与 Kiana 当前所在岛屿的欧几里德距离最多为船只的当前容量，就可以访问该岛屿。 

岛屿数量少于 1000 个。这立即排除了探索每条可能的路线，因为可能的岛屿订单数量可能非常巨大。 二次解是可以接受的，因为 1000 的平方仅为一百万次运算，这对于一秒的限制来说很小。 

主要的边缘情况来自于像普通图搜索一样处理问题。 该图本身取决于迄今为止收集的物资数量，因此在开始时构建一次边缘可能会给出不正确的结果。 例如：```
3
0 0 5
4 0 10
10 0 0
```正确的输出是：```
YES
```第一个岛可以到达第二个岛，因为距离为4。再收集10个补给后，容量变为15，可以到达目的地。 仅考虑初始容量的粗心实现会错误地拒绝该路由。 

另一个边缘情况是仍然需要零供应岛屿的链。```
3
0 0 3
3 0 0
6 0 0
```正确的输出是：```
YES
```第一跳完全可以，第二跳同样容量也可以。 仅考虑增加范围的孤岛的实现将错过有效路径。 

第三个常见错误是忽略起始岛屿的补给或添加两次。```
2
0 0 5
5 0 0
```正确的输出是：```
YES
```目的地正好在初始极限处。 起始供应已激活，必须计数一次。 

## 方法

 直接的暴力方法会尝试从起始岛开始的所有可能的路线。 对于当前的每个岛屿，它将尝试所有未使用的岛屿，并在距离可达时递归地继续。 这是正确的，因为它检查每个可能的访问序列，但路线数量呈阶乘增长。 岛屿有近 1000 个，即使考虑所有可能路径中的一小部分也是不可能的。 

看待这个问题的一个更有用的方法是停止关心已经收集的岛屿的确切顺序。 在任何时刻，影响未来行动的唯一信息是当前可到达的岛屿组以及从这些岛屿收集的总补给量。 由于补给永远不会被移除，每一个新到达的岛屿只会让未来的行动变得更加容易。 

这就给出了一个贪婪的扩张过程。 从访问的第一个岛屿开始，重复收集当前可到达的每个岛屿。 每个收集的岛屿都会增加容量，这可能会揭示更多可到达的岛屿。 当收集到目的地或无法到达新岛屿时，该过程结束。 

我们不需要首先选择一个特殊的岛屿的原因是，访问任何当前可到达的岛屿都不会造成伤害。 它只会增加供应，而不会减少未来可能采取的行动。 延迟到达岛屿没有任何好处，因为同一岛屿稍后仍可使用相同或更大的容量。 

该实施保持了每个未访问过的岛屿与任何访问过的岛屿之间的最小距离。 只要该最小距离最多为当前容量，就可以添加该岛。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 最坏情况下的 O(N!) | O(N) 递归堆栈 | 太慢了 |
 | 最佳| O(N²) | O(N²) | 已接受 |

 ## 算法演练

 1. 读取所有岛屿并预先计算每对岛屿之间的平方距离。 与船的容量进行比较时，平方距离可以避免浮点误差。 
2. 将起始岛屿标记为已访问，并将当前容量设置为其补给量。 启动物资已经安装在船上。 
3. 重复扫描每个未访问过的岛屿。 如果存在距离在当前容量范围内的已访问岛屿，则将该岛屿标记为已访问并将其补给添加到容量中。 
4. 继续扩展，直到无法添加新岛屿或无法访问目的地为止。 
5、输出`YES`如果到达目的地，否则输出`NO`。 

这种贪婪扩张有效的原因是，所访问的岛屿构成了当前收集的补给量可以到达的最大集合。 如果某个岛屿在某个时刻可以到达，那么尽早收集它只会增加可用容量。 该算法永远不会跳过可能的改进，因此当它停止时，每个未访问过的岛屿实际上都是无法到达的。 

为什么它有效：

 保持不变，即使用已标记为已访问的岛屿即可到达每个已访问的岛屿。 该算法仅在验证可以乘船前往该岛后才添加一个岛屿，因此不变式仍然为真。 当添加一个岛屿时，其供应会增加容量，这意味着以前可能的所有移动仍然可能。 如果从未添加目的地，则最终扫描证明从当前可到达区域无法到达未访问过的岛屿，因此不存在延续。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)

    islands = []
    for _ in range(n):
        x, y, s = map(int, input().split())
        islands.append((x, y, s))

    dist = [[0] * n for _ in range(n)]
    for i in range(n):
        xi, yi, _ = islands[i]
        for j in range(i + 1, n):
            xj, yj, _ = islands[j]
            d = (xi - xj) ** 2 + (yi - yj) ** 2
            dist[i][j] = d
            dist[j][i] = d

    visited = [False] * n
    visited[0] = True
    capacity = islands[0][2]
    remaining = n - 1

    while remaining:
        changed = False
        for i in range(1, n):
            if visited[i]:
                continue
            reachable = False
            for j in range(n):
                if visited[j] and dist[i][j] <= capacity * capacity:
                    reachable = True
                    break
            if reachable:
                visited[i] = True
                capacity += islands[i][2]
                remaining -= 1
                changed = True

        if visited[n - 1]:
            print("YES")
            return
        if not changed:
            break

    print("YES" if visited[n - 1] else "NO")

if __name__ == "__main__":
    solve()
```第一部分计算平方距离。 使用平方值可以避免重复调用平方根，并避免距离恰好在边界上时出现精度问题。 

访问的数组代表已经收集了补给的岛屿。 容量变量是船当前在一次连续行程中可以行驶的总英里数。 

主循环执行贪婪扩展。 每个通道都会尝试找到从当前访问的区域可以到达的岛屿。 添加岛屿后，其补给会立即影响同一通道或未来通道中的后续检查。 

比较使用`dist[i][j] <= capacity * capacity`因为`dist`存储平方距离。 平等的情况被包括在内，因为完全按照船的极限到达岛屿是允许的。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N²) | 每次扩展都会检查成对的岛屿，最多有 N 次成功添加。 |
 | 空间| O(N²) | 距离矩阵存储每对岛屿。 |

 由于岛屿数量少于 1000 个，距离矩阵包含约 100 万个条目，非常适合内存。 对于给定的限制，二次扫描也足够小。

 ## 边缘情况

 对于零供应链：```
3
0 0 3
3 0 0
6 0 0
```该算法从容量 3 开始。添加岛屿 1，因为其距离平方为 9，等于容量平方。 容量仍为 3，但岛 1 现在是一个新位置，岛 2 距岛 2 的距离也为 3。已到达目的地。 

对于新补给解锁遥远岛屿的情况：```
3
0 0 5
4 0 10
15 0 0
```第一个岛可以到达第二个岛。 收集 10 个补给后，容量变为 15，从而可以到达目的地。 该算法发现这一点是因为新访问的岛屿会立即包含在以后的可达性检查中。 

对于精确的边界移动：```
2
0 0 5
5 0 0
```距离的平方是 25，容量的平方也是 25。比较使用`<=`，因此该岛被正确地认为是可达的。 严格比较会得出错误的答案。
