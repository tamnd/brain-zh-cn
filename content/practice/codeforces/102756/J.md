 ## 解决方案
 ## 问题理解

 我们有一行$N$雕像。 每个雕像都由一个描述$K$-位数，其中位$i$告诉是否有特征$i$出现在那个雕像上。 当一组连续的雕像中每个特征在该组中出现相同的次数时，该组被称为雄伟的。 任务是找到这样一个连续组的最大可能长度。 

输入尺寸很大：$N$可以达到$100000$， 尽管$K$可以大到$30$。 检查每个间隔的解决方案将检查周围$N^2$范围，大约是$10^{10}$为最大输入。 即使更新每个范围的特征计数也会太慢。 我们需要一种近线性的方法。 的小值$K$告诉我们，表示有关特征的信息是可能的，但我们无法存储所有可能的特征计数组合。 

一个常见的错误是只检查设置的位数是否平衡。 这还不够，因为每个单独的特征都必须具有相同的频率。 

例如：```
4 3
1
2
4
7
```正确答案是`1`。 长度为 2 的段，例如`[1, 2]`每个功能都出现一次吗？ 不会。特征 1 出现一次，特征 2 出现一次，但特征 3 出现零次。 条件是所有三个特征计数相等，而不是特征总数。 

另一个边缘情况是$K=1$:```
5 1
0
1
0
1
1
```正确答案是`5`。 如果只有一项功能，每个范围都会自动具有相等的计数，因为只有一个计数可供比较。 始终构建大小差异向量的实现$K-1$必须单独处理这种情况。 

第三个重要的例子是从第一座雕像开始的雄伟范围：```
3 2
1
2
3
```正确答案是`3`。 前缀哈希解决方案必须在处理任何状态之前存储空前缀，否则它们无法检测从索引 1 开始的范围。 

## 方法

 直接解决方案会尝试所有可能的间隔。 对于每个左端点，我们扩展右端点并维护每个特征的计数。 每当所有$K$计数相等，我们更新答案。 这是正确的，因为考虑了所有可能的范围。 然而，有$O(N^2)$范围，并检查之间的相等性$K$计数器做了最坏的情况$O(N^2K)$。 和$N=100000$，这远远超出了可用时间。 

关键的观察是避免存储实际计数。 如果所有特征数都相等，则范围是巨大的。 我们可以将每个特征与一个选定的参考特征进行比较，而不是询问每个计数是否具有相同的值。 

选择特征零作为参考。 对于数组的每个前缀，存储差异：$$count_1-count_0,\ count_2-count_0,\ ...,\ count_{K-1}-count_0$$如果两个前缀具有相同的差异向量，则这些前缀之间的雕像将相同的数量添加到每个特征计数中。 两个相等的前缀向量之间的差异使得每个特征计数相等，这意味着该片段是巨大的。 

这将问题转化为寻找具有相同前缀状态的最长子数组，这可以通过存储每个状态第一次出现的哈希图来解决。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(N^2K)$|$O(K)$| 太慢了 |
 | 前缀差异哈希 |$O(NK)$|$O(NK)$| 已接受 |

 ## 算法演练

 1.阅读雕像并处理特殊情况$K=1$。 每个区间都是有效的，所以答案是$N$。 
2. 维护一个长度的前缀差分向量$K-1$。 处理雕像时，添加$1$到与其包含的特征相对应的每个位置（参考特征除外）。 如果雕像包含参考特征，则减去$1$与其他所有功能的差异。 

该向量始终表示当前前缀中每个非参考特征计数与参考特征计数的差异程度。 
3. 存储每个差异向量出现的第一个索引。 空前缀具有全零向量并存储在索引零处。 
4. 当前缀向量再次出现时，第一次出现和当前位置之间的段具有相等的特征计数。 使用这些位置之间的距离作为可能的答案。 
5. 继续，直到处理完所有雕像并输出找到的最大长度。 

为什么它有效：

 存储的向量恰好包含比较特征计数所需的信息。 如果两个前缀具有相同的向量，则这些前缀之间的变化会使每个特征具有相同的频率，因为相对于参考特征的所有差异都会抵消。 相反，如果一个范围很大，则每个特征计数在该范围内均匀变化，因此该范围前后的前缀差异向量必须相同。 哈希映射准确地找到了这些前缀对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n, k, arr):
    if k == 1:
        return n

    first = {tuple([0] * (k - 1)): 0}
    diff = [0] * (k - 1)
    ans = 0

    for idx, x in enumerate(arr, 1):
        has_first = x & 1

        if has_first:
            for i in range(k - 1):
                diff[i] -= 1

        for i in range(1, k):
            if x & (1 << i):
                diff[i - 1] += 1

        state = tuple(diff)

        if state in first:
            ans = max(ans, idx - first[state])
        else:
            first[state] = idx

    return ans

def main():
    data = sys.stdin.read().split()
    if not data:
        return

    ptr = 0
    out = []

    while ptr < len(data):
        n = int(data[ptr])
        k = int(data[ptr + 1])
        ptr += 2

        arr = list(map(int, data[ptr:ptr + n]))
        ptr += n

        out.append(str(solve_case(n, k, arr)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```该实现保留每个前缀状态的第一次出现，因为较早的出现总是给出更长的有效段。 元组转换是必要的，因为列表是可变的并且不能是字典键。 

参考特征经过特殊处理。 当它出现时，每个差异都会减少，因为引用计数增加了 1。 对于其他功能，只有当该位存在时，它们的位置才会增加。 这些更新的顺序不会影响最终的差异向量，因为每个雕像只贡献一次。 

在处理任何雕像之前插入空前缀。 这处理从第一个雕像开始的范围，并防止长度计算中出现差一错误。

 ## 边缘情况

 对于$K=1$，算法立即返回，因为不需要在特征之间进行比较。 每个雕像范围都有一个特征计数，因此条件始终为真。 

对于从第一个雕像开始的范围，零前缀状态表示读取任何内容之前的状态。 在输入中：```
3 2
1
2
3
```三个雕像全部归零后的状态，与存储的初始状态匹配。 该算法正确计算长度为$3-0=3$。 

对于每个特征计数必须单独匹配的情况，差异向量可以防止误报。 在：```
4 3
1
2
4
7
```基于总特征计数的方法可能会错误地认为一些较长的片段有效，但存储的差异表明，直到只剩下单个雕像，三个特征计数才会平衡。 答案正确地找到为`1`。
