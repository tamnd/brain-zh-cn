 ## 解决方案
 ## 问题理解

 这个问题要求我们检查一系列历史发明。 每项发明都有名称、发明日期和代表其与切片面包相比的好坏程度的分数。 我们需要在切片面包之后创造的发明中找到最伟大的发明，该发明被认为是1928年7月7日发明的。答案是这些符合条件的发明中得分最高的发明名称。 

输入包含多达 10,000 个发明描述。 每个描述占据三行：发明标题、人类可读的月份格式的日期和小数分数。 由于发明的数量只有 10,000 个，线性扫描很容易足够快。 在最坏的情况下，任何比较每对发明的方法都会执行大约 1 亿次比较，这对于如此简单的选择问题来说是不必要的。 

主要困难不是数据的大小，而是正确处理日期和过滤。 一个常见的错误是在阅读时立即选择最大的分数，而不检查发明是否发生在切片面包之后。 另一个错误是直接比较日期字符串。 例如，日期“1930 年 12 月 1 日”和“1931 年 1 月 1 日”不能正确排序为字符串，因为月份名称不是按时间顺序排序的。 

当最高分属于切片面包之前的发明时，就会出现边缘情况。 考虑这个输入：```
3
Ancient Fire
Apr 20, 960
0.99999
Radio
Dec 26, 1933
0.65
Hovercraft
Dec 12, 1955
0.896
```正确的输出是：```
Hovercraft
```仅跟踪最高分数的粗心实现会错误地打印“Ancient Fire”。 日期过滤必须在比较分数之前进行。 

另一个极端情况是恰好在 1928 年 7 月 7 日创建的发明。该发明不被视为自切片面包以来的发明，因为只有该天之后的日期才符合条件。 例如：```
2
Exact Date
Jul 7, 1928
1.0
Future Item
Jan 1, 1929
0.5
```输出必须是：```
Future Item
```只有在确认发明严格晚于参考日期后才应进行分数比较。 

## 方法

 最简单的解决方案是检查每一项发明并保留迄今为止发现的最合格的发明。 这是正确的，因为答案只是过滤后的集合中的最大分数。 对于每项发明，我们首先检查其日期是否在 1928 年 7 月 7 日之后。如果是，我们将其得分与当前的最佳得分进行比较，并在必要时替换答案。 

强力方法可以将每一项发明与其他符合条件的发明进行比较，以确定哪一项得分最高。 这仍然是正确的，但对于 10,000 项发明，可能需要大约 1 亿次分数比较。 它还忽略了这样一个事实：找到最大值不需要知道每对元素之间的关系。 

关键的观察结果是该问题在发明之间没有相互作用。 最佳发明的选择仅取决于每个发明的资格和分数。 这使我们能够在读取输入时保持单个运行最大值。 日期解析将每个日期转换为数字表示形式，使时间比较可靠。 

蛮力方法之所以有效，是因为它最终发现了最大值，但它失败了，因为它重复了不必要的比较。 观察到可以增量地维持最大值，从而将整个任务减少为一次通过输入。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N²) | O(1) | O(1) | 对于一般情况来说太慢了 |
 | 最佳 | O(N) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取发明数量并初始化变量来存储最好成绩和对应的标题。 
2. 一次处理一项发明。 阅读其标题、日期和分数，因为没有必要存储所有发明。 
3. 将日期转换为可比较的数字形式。 月份名称转换为月份编号，日期变为包含年、月、日的元组。 这种表示自然遵循时间顺序。 
4. 检查发明日期是否严格大于 1928 年 7 月 7 日。如果不是，则忽略该发明，因为它不符合条件。 
5. 对于每项符合条件的发明，将其得分与当前最好得分进行比较。 如果分数较大，则更新存储的答案。 
6. 处理完所有发明后，打印存储的标题。 

单个存储答案就足够的原因是，在处理输入的任何前缀之后，存储的发明始终是该前缀中看到的最佳有效发明。 当处理另一项发明时，要么它更糟并且当前答案保持正确，要么它更好并且替换答案恢复相同的属性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    months = {
        "Jan": 1,
        "Feb": 2,
        "Mar": 3,
        "Apr": 4,
        "May": 5,
        "Jun": 6,
        "Jul": 7,
        "Aug": 8,
        "Sep": 9,
        "Oct": 10,
        "Nov": 11,
        "Dec": 12,
    }

    sliced_bread_date = (1928, 7, 7)

    best_score = -1.0
    best_title = ""

    for _ in range(n):
        title = input().rstrip("\n")
        date_line = input().strip()
        score = float(input().strip())

        month, day_year = date_line.split(" ", 1)
        day, year = day_year.replace(",", "").split()

        date = (int(year), months[month], int(day))

        if date > sliced_bread_date and score > best_score:
            best_score = score
            best_title = title

    print(best_title)

if __name__ == "__main__":
    solve()
```月份字典将文本月份转换为整数，这使得日期比较独立于字符串排序。 元组格式`(year, month, day)`之所以有效，是因为 Python 从左到右比较元组元素，与正常日历比较中使用的顺序相匹配。 

分数存储为浮点数，因为输入给出的是十进制评级。 由于最伟大的有效发明之间没有联系，因此简单的严格比较就足够了。 初始分数为`-1.0`保证第一个有效的发明将取代占位符。 

日期条件使用`>`而不是`>=`。 这正确地处理了边界规则，因为 1928 年 7 月 7 日的发明并不被认为比切片面包更新。 

该算法从不存储完整的发明列表。 它只保留当前的最佳标题和分数，从而保持内存使用量恒定。

 ## 边缘情况

 第一个棘手的情况是当一项较旧的发明得分非常高时。 对于输入：```
3
Ancient Fire
Apr 20, 960
0.99999
Radio
Dec 26, 1933
0.65
Hovercraft
Dec 12, 1955
0.896
```该算法首先拒绝Ancient Fire，因为它的日期元组是`(960, 4, 20)`，小于`(1928, 7, 7)`。 然后它比较两个有效的发明并保留气垫船，因为`0.896`大于`0.65`。 

第二种情况是确切的切片面包日期：```
2
Exact Date
Jul 7, 1928
1.0
Future Item
Jan 1, 1929
0.5
```第一个发明产生了元组`(1928, 7, 7)`，它等于参考日期，因此严格比较会拒绝它。 第二项发明产生`(1929, 1, 1)`并成为答案。 这可以防止错误地处理边界条件。
