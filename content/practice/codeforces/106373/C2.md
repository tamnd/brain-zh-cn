 ## 解决方案
 ## 问题理解

 我们得到一个由小写字符组成的字符串。 任务是分析其所有连续的子字符串，并计算其中有多少是“全局意义上唯一的”，这意味着每个计数的子字符串在原始字符串中只出现一次。 

为了使操作更加精确，想象一下通过开始和结束位置枚举每个子字符串。 某些子字符串可能在多个位置重复，而其他子字符串仅出现在单个位置。 输出是整个字符串中总频率恰好为 1 的子字符串的数量。 

约束（此类问题中字符串长度最多可达典型的 Codeforces 几十万范围）立即排除了任何显式枚举子字符串的解决方案。 即使存储所有子串在内存中也是二次方，而简单地计算它们的频率在时间上也是三次方。 

一个关键的结构困难是子串严重重叠。 如果我们尝试直接比较子字符串，我们最终会重复重新计算大型重叠段之间的相等性。 

一些边缘案例说明了天真的推理在哪里失效。 考虑一个像这样的字符串`aaaaa`。 每个长度大于 1 的子字符串都会重复多次，因此只有单个字符起作用，甚至这些字符也不是唯一的，因为每个字符出现多次。 因此正确答案是零。 仅检查子字符串是否存在于其他地方而不仔细跟踪多重性的简单方法将错误地计算许多重复的单字符子字符串。 

另一个边缘情况是像这样的字符串`abc`。 每个子字符串都只出现一次，因为所有字符都是不同的，因此答案等于子字符串的总数，对于长度为 3 的字符串，其结果为 6。 任何只计算不同子串而不计算出现频率的方法都会忽略这里每个不同子串的频率也是唯一的。 

最后，混合重复的情况，如`ababa`这是错误的贪婪推理经常失败的地方。 子串如`aba`由于重叠而多次出现，尽管它们的内部结构看起来“多种多样”，因此结构的独特性是不够的，只有全局出现次数才重要。 

## 方法

 直接的暴力解决方案将枚举每个子字符串，存储它，并使用哈希图计算频率。 这会立即产生 O(n²) 子字符串，并且在最坏的情况下比较或散列每个子字符串的成本为 O(n)，从而导致 O(n³) 时间。 即使使用滚动哈希，我们仍然面临 O(n²) 子串和巨大的内存压力。 这种方法在概念上是正确的，但在计算上不可行。 

关键的见解是我们不应该将子字符串视为独立的对象。 相反，我们按照“字符串中出现的同一组”的等价类对子字符串进行分组。 这正是后缀自动机的设计目的。 

后缀自动机将字符串的所有子串压缩为 O(n) 状态。 每个状态代表一组共享同一组结束位置的子字符串，这意味着它们出现在原始字符串中完全相同的位置。 自动机还跟踪转换和按长度间隔划分子字符串的后缀链接树。 

一旦我们构建了自动机，每个状态就知道它对应多少个结束位置。 如果某个状态恰好对应于一个结束位置，则该状态表示的每个子字符串在原始字符串中恰好出现一次。 一个状态贡献的此类子串的数量是其最大长度和最小长度之间的差值，自然编码为`len[state] - len[link[state]]`。 

这减少了从枚举子字符串到迭代自动机状态的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n3)（或 O(n2 log n)，使用散列）| O(n²) | 太慢了|
 | 后缀自动机 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 在字符串上构建后缀自动机。 每个状态代表一组共享相同结束位置的子串。 这种构造将字符一一处理，扩展了自动机，同时保持了过渡结构和后缀链接。 
2. 为每个状态维护一个在构造期间初始化的频率计数器。 每次插入新字符时，我们都会标记当前的终止状态。 这确保了字符串中的每个位置都有助于计算其相应状态的结束位置。 
3. 构建自动机后，按长度递减顺序将计数从较长状态传播到后缀链接状态。 此步骤累积每个状态作为字符串中的结束位置出现的次数。 
4. 传播完成后，每个状态都有一个正确的出现次数，表示其子字符串在原始字符串中出现的次数。 
5. 对于出现次数恰好等于 1 的每个状态，添加其贡献`len[state] - len[link[state]]`到最终的答案。 
6. 输出累加和。 

我们使用的原因`len[state] - len[link[state]]`是每个状态覆盖连续区间中的所有子串长度。 后缀链接指向最大的真后缀状态，长度的差精确地计算出该状态引入了多少个不同的子串长度。 

### 为什么它有效

 后缀自动机将所有子串划分为不相交的等价类，其中每个类对应于一个状态。 在一个状态内，所有子串共享相同的出现集，因此它们要么全部只出现一次，要么全部出现多次。 这消除了各个子字符串的歧义。 贡献公式对每个子串恰好计数一次，因为每个子串恰好属于一个状态并且恰好属于该状态内的一个长度区间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class State:
    __slots__ = ("next", "link", "len", "cnt")
    def __init__(self):
        self.next = {}
        self.link = -1
        self.len = 0
        self.cnt = 0

class SuffixAutomaton:
    def __init__(self, s):
        self.st = [State() for _ in range(2 * len(s))]
        self.size = 1
        self.last = 0

        for ch in s:
            self.extend(ch)

        self.order = sorted(range(self.size), key=lambda i: self.st[i].len, reverse=True)
        self.process_counts()

    def extend(self, c):
        cur = self.size
        self.size += 1
        self.st[cur].len = self.st[self.last].len + 1
        self.st[cur].cnt = 1

        p = self.last
        while p != -1 and c not in self.st[p].next:
            self.st[p].next[c] = cur
            p = self.st[p].link

        if p == -1:
            self.st[cur].link = 0
        else:
            q = self.st[p].next[c]
            if self.st[p].len + 1 == self.st[q].len:
                self.st[cur].link = q
            else:
                clone = self.size
                self.size += 1

                self.st[clone].len = self.st[p].len + 1
                self.st[clone].next = self.st[q].next.copy()
                self.st[clone].link = self.st[q].link

                while p != -1 and self.st[p].next.get(c) == q:
                    self.st[p].next[c] = clone
                    p = self.st[p].link

                self.st[q].link = self.st[cur].link = clone

        self.last = cur

    def process_counts(self):
        for i in self.order:
            link = self.st[i].link
            if link != -1:
                self.st[link].cnt += self.st[i].cnt

s = input().strip()
sam = SuffixAutomaton(s)

ans = 0
for v in range(1, sam.size):
    if sam.st[v].cnt == 1:
        link = sam.st[v].link
        ans += sam.st[v].len - sam.st[link].len

print(ans)
```自动机构造是标准的：每个角色都会扩展最后一个状态，在分割转换时可能会创建一个新状态或克隆状态。 这`cnt`字段在终端状态初始化，然后以长度递减的顺序沿着后缀链接推送，这保证了较长的子字符串在较短的子字符串聚合它们之前正确地传播它们的计数。 

最后的循环小心地排除初始状态，因为它代表空字符串，并且仅对与仅出现一次的子字符串相对应的状态的贡献求和。 

## 工作示例

 ### 示例 1：`abc`| 步骤| 状态长度 | cnt 值（简化）| 添加贡献 |
 | --- | --- | --- | --- |
 | 构建后 | a、b、c 及其组合的多种状态 | 所有叶状态的 cnt = 1 | 传播后计算 |

 传播后，每个状态都对应于只出现一次的子串。 所有子串的贡献之和：`a, b, c, ab, bc, abc`。 

这证实了每个子串都被精确地分配给一个状态并计数一次的不变量。 

### 示例 2：`aba`| 步骤| 状态| 碳纳米管| 贡献 |
 | --- | --- | --- | --- |
 | 构建后 | a、b、ab、ba、aba 的状态 | 混合 | 待定 |
 | 传播后| 一些州的 cnt = 1 | 过滤| 仅计算唯一出现的子字符串 |

 在这里，子字符串像`a`出现两次并被排除，而`b`,`ab`,`ba`,`aba`被适当地计算。 

这表明重叠并不重要，只有全局频率编码在`cnt`。

 | 测量 | 复杂性 | 说明|

 | 时间 | O(n) | 每个字符在后缀自动机中插入一次，并且在计数传播期间每个状态处理一次 |

 ## 边缘情况

 对于一串相同的字符，例如`aaaaa`，后缀自动机中的每个状态（除了前几个状态）都会折叠成单个重复结构。 在传播过程中，每个状态的计数都大于 1，因此没有状态满足条件`cnt == 1`，答案正确地变成零。 该算法可以处理这个问题，因为频率是全局累积的，而不是从结构推断的。 

对于具有所有不同字符的字符串，例如`abcde`，每个子字符串对应于自动机中的唯一路径，并且每个状态接收的计数恰好为 1。 因此，每个状态都贡献其全长间隔，最终的总和等于子串的总数。 这证实了自动机不会人为地合并不同的子串。 

对于混合重叠的情况，例如`ababa`, 状态代表`aba`和`ba`由于重叠位置重复出现，累积计数大于 1。 传播步骤确保这些重复项正确反映在`cnt`，防止错误地包含在最终总和中。
