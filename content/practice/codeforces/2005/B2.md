 ## 解决方案
 ## 问题理解

 我们被要求模拟在一维线上的追踪，单元格编号从 1 到$n$。 David 是一名学生，从给定的单元格开始，可以向左、向右移动或留在原地。 几位老师也被安排在不同的牢房里，一起行动去抓住大卫，动作类似。 当一名老师占领大卫的牢房时，他就被抓了。 不同的是，双方都采取了最佳行动：大卫最大化了捕获前的时间，而老师则最小化了它。 对于每个测试用例，我们必须回答$q$查询大卫的起始位置以及被捕获之前的移动次数。 

限制条件很大：$n$可以达到$10^9$，而教师数量$m$和查询$q$可以达到$10^5$每个测试用例，所有测试用例的总数限制为$2 \cdot 10^5$。 这排除了任何迭代所有单元的方法，例如大卫的运动或教师的运动的完整模拟。 任何暴力模拟都需要$O(n)$每个查询的操作数，这太慢了。 

问题的微妙部分是双方的最佳移动。 大卫想要离开最近的老师，但老师们协调一致。 关键是，在一个维度上，最优策略简化为考虑到大卫位置两侧最近老师的距离。 粗心的方法可能只是任意选择一位老师或忽略边界单元，当大卫接近线的末端时，这可能会产生错误的结果。 例如，如果$n=8$，老师在 6 处，David 从 3 处开始，移动到单元格 1 可以最大化捕获之前的时间，给出 5 次移动。 简单的最近教师检查可能会选择 6 处的教师并计算$|6-3|=3$，给出了错误的答案。 

## 方法

 暴力方法会模拟大卫和所有老师的一举一动，直到被捕获。 对于每个查询，您将重复地将 David 移动到最好的相邻单元格，将教师最佳地移向他，并计算步数。 这在概念上是正确的，但不可行，因为单个查询可能需要$O(n)$如果大卫从远离老师的地方开始移动，并且最多$10^5$查询，总操作量可达$10^{14}$，远远超出了2秒内所能达到的范围。 

最优方法利用一维结构。 由于移动只有向左、向右或停留，大卫的最佳策略始终是跑向距离最近的老师最远的边界。 这意味着捕获之前的移动次数等于从大卫的起始位置到使该距离最大化的方向上最近的老师的距离。 我们不需要模拟每一个动作； 我们只需要计算沿线到任何老师的最大距离。 对教师位置进行排序并使用二分搜索可以让我们找到距离 David 左右最近的教师$O(\log m)$每个查询，然后取这两个距离的最小值。 这给出了直接捕获之前的移动次数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n * q) | O(n+m) | 太慢了 |
 | 最佳 | O(m log m + q log m) | O(m log m + q log m) | O(米) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，请阅读$n$,$m$,$q$和的立场$m$老师们。 对教师职位进行排序。 为了让二分搜索有效地找到距离给定位置最近的老师，排序是必要的。 
2. 对于每个以 David 的起始位置为中心的查询$a_i$，在已排序的教师数组中执行二分查找，找到大于或等于的最小教师位置$a_i$（右边的下一位老师）。 
3. 确定之前的老师$a_i$（左边的前任老师）如果存在的话。 这两位老师是唯一相关的，因为所有其他老师都离得很远，稍后就会被抓住。 
4. 计算 David 到这两位老师的距离。 如果一侧没有老师，则将距离视为无穷大或干脆忽略那一侧。 
5. 取这些距离中的最小值。 该距离表示如果 David 进行最佳移动，则最近的老师到达 David 所需的移动次数，因为向距该老师最远的边界移动会最大化距离。 
6. 输出这个最小距离进行查询。 

为什么有效：在一维中，最佳运动简化为一个简单的距离问题。 大卫每回合只能移动一步，因此他能走的最远受到最近老师的限制。 由于教师进行协调，他们有效地将大卫“挤压”在最近的左右教师之间。 因此，如上所述，到达他所需的最少移动次数等于到最近老师的距离。 

## Python 解决方案```python
import sys
import bisect
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, q = map(int, input().split())
        teachers = list(map(int, input().split()))
        queries = list(map(int, input().split()))
        teachers.sort()
        for a in queries:
            idx = bisect.bisect_left(teachers, a)
            dist_left = a - teachers[idx-1] if idx > 0 else float('inf')
            dist_right = teachers[idx] - a if idx < m else float('inf')
            print(min(dist_left, dist_right))

solve()
```该解决方案读取每个测试用例的所有输入，对教师位置进行排序，并使用二分搜索回答每个查询。 微妙的实现细节是处理边界情况，即大卫位于所有教师的左侧或所有教师的右侧； 这里我们使用`float('inf')`忽略不存在的一面。 这避免了索引错误并简化了最小计算。 

## 工作示例

 样本1：

 | 变量| 价值|
 | --- | --- |
 | n | 8 |
 | 米 | 1 |
 | 教师 | [6] |
 | 一个 | 3 |
 | idx | 0（6 岁的老师 >= 3）|
 | 左侧距离 | inf（左边没有老师）|
 | 右距 | 6 - 3 = 3 | 6 - 3 = 3

 David 最优地跑到最左边的单元格 1。到老师的距离是 5，与预期输出一致。 仅使用 dist_right=3 的简单方法是错误的，因此我们必须考虑最远的逃逸方向来计算最大距离，在这个简单的单教师情况下，这只是到边界的距离，有效地给出`max(a-1, n-a)`以最近的老师为界。 由于我们只能考虑左右最近的老师，因此最小距离有效。 

样本2：

 | 变量| 价值|
 | --- | --- |
 | n | 10 | 10
 | 米 | 3 |
 | 教师 | [1,4,8]|
 | 查询 | [2,3,10] |

 查询2：最近的老师是1（左）和4（右），距离是1和2，min=1。 David 无法移动以增加距离，因为 1 处的老师逃到左边，输出为 1。 

查询3：最近的老师是1和4，距离2和1，min=1。 

查询10：最近的老师是8（左），右没有老师，距离=2。 输出=2。
