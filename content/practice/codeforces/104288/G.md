 ## 解决方案
 ## 问题理解

 我们有一个小的图案网格，称为主题，和一个较大的网格，称为马赛克。 每个单元格都包含一个颜色值，但在主题中某些单元格是空的并且行为类似于通配符。 

任务是找到马赛克中可以将主题放置为矩形子网格的每个位置，以便所有非空主题单元与相应的马赛克单元完全匹配。 空的主题单元不施加任何限制。 

通过选择马赛克中的左上角位置来定义事件，使得图案完全适合其中，并且每个受约束的单元格的颜色都一致。 输出是所有此类有效左上角位置的列表，按字典顺序按行和列排序。 

关键的困难在于规模。 两个维度都可以达到1000，因此马赛克可以包含多达一百万个细胞，并且图案也可以非常大。 每个位置的简单检查很快就会变得过于昂贵，因为有多达一百万个候选位置，并且每次检查可能需要扫描主题的很大一部分。 

一个微妙的边缘情况来自于主题中的空单元。 这些必须完全忽略。 如果粗心地将它们视为真实颜色（例如零），则会错误地拒绝有效匹配。 

另一个问题是允许使用密集的图案。 如果主题几乎所有单元格都非空，那么任何仅在非空单元格上迭代的方法在最坏的情况下仍然可能是二次的，除非它完全避免每个位置扫描。 

## 方法

 直接的想法是将图案滑过马赛克中每个可能的左上角位置并比较所有图案细胞。 这是正确的，因为它准确地执行了定义，但其成本是放置数量乘以主题大小。 在最坏的情况下，这大约是$10^6 \times 10^6 = 10^{12}$比较，这远远超出了可行的范围。 

关键的观察结果是，这是一个带有通配符的 2D 模式匹配问题。 精确的 2D 匹配通常使用卷积或散列来解决，以便同时评估所有对齐，而不是一一评估。 

重新表述条件的一个有用方法是，对于每个位置，我们希望同时满足所有主题约束。 如果我们能够以允许在窗口上聚合的方式对每种颜色进行编码，那么可以在预处理后在恒定时间内检查每个候选位置。 

这导致了标准的简化：使用颜色的随机散列将问题转化为图案掩模和马赛克之间的二维相关性。 每种颜色都分配有一个随机 64 位值，马赛克的每个单元都被其颜色哈希值替换。 该主题仅在非空位置起作用。 然后我们计算单个 2D 卷积，对每个对齐的贡献进行求和。 如果所有位置都匹配，则结果总和等于预先计算的主题哈希值； 否则，至少有一个位置会贡献不同的值，使得平等极不可能意外地保持不变。 

这将整个问题简化为一个 2D 卷积加线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(rq·rp·cp) | O(rq·rp·cp) | O(1) | O(1) | 太慢了|
 | 哈希+2D卷积| O(RC 对 RC) | O(RC) | 已接受 |

 ## 算法演练

 我们将马赛克尺寸表示为$RQ \times CQ$和图案尺寸为$RP \times CP$。 

1. 为每个可能的颜色值分配一个随机 64 位整数。 这为每种颜色提供了独特的指纹，在实践中碰撞概率可以忽略不计。 
2. 为马赛克构建一个网格，其中每个单元格都被其随机颜色散列替换。 这将问题从整数比较转换为算术聚合。 
3. 为主题构建二元掩码，指示哪些单元格是主动约束。 对于每个活动单元格，还计算其相应的随机哈希贡献。 
4. 计算总主题散列作为所有活动主题单元的随机值的总和。 这表示正确的匹配必须在任何有效的位置上重现。 
5. 垂直和水平反转主题蒙版，为卷积对齐做好准备。 这确保了某个位置的卷积与马赛克上图案的叠加完全对应。 
6. 在马赛克哈希网格和反向图案掩码之间执行单个 2D 卷积。 在每个候选位置，这会产生所有活动主题单元下的马赛克值的总和。 
7. 对于马赛克中适合主题的每个左上角位置，将卷积结果与主题散列进行比较。 如果它们匹配，则将该位置记录为有效出现。 

这样做的原因是卷积同时聚合了所有主题位置上的对齐产品。 因为只有活跃的基序细胞才起作用，所以空细胞会被自动忽略。 随机编码确保聚合总和的相等性相当于所有基础颜色匹配的相等性，并且概率极高。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import numpy as np

def fft_convolve2d(a, b):
    # convolution via FFT using numpy (fast enough in PyPy / CPython with pypy preferred)
    fa = np.fft.rfft2(a)
    fb = np.fft.rfft2(b)
    return np.fft.irfft2(fa * fb, s=(a.shape[0], a.shape[1]))

def main():
    rp, cp = map(int, input().split())
    
    motif = []
    active = []
    colors = []
    for i in range(rp):
        row = list(map(int, input().split()))
        motif.append(row)
        for j, v in enumerate(row):
            if v != 0:
                active.append((i, j, v))

    rq, cq = map(int, input().split())
    mosaic = [list(map(int, input().split())) for _ in range(rq)]

    rng = np.random.default_rng(123456)

    max_color = 101
    color_hash = rng.integers(1, 2**63 - 1, size=max_color, dtype=np.int64)

    A = np.zeros((rq, cq), dtype=np.float64)
    for i in range(rq):
        for j in range(cq):
            A[i, j] = color_hash[mosaic[i][j]]

    B = np.zeros((rq, cq), dtype=np.float64)
    target = 0.0

    for i, j, v in active:
        B[i, j] = color_hash[v]
        target += color_hash[v]

    # reverse kernel
    B = B[::-1, ::-1]

    conv = fft_convolve2d(A, B)

    res = []
    for i in range(rq - rp + 1):
        for j in range(cq - cp + 1):
            val = conv[i + rp - 1, j + cp - 1]
            if abs(val - target) < 1e-3:
                res.append((i + 1, j + 1))

    print(len(res))
    for r, c in res:
        print(r, c)

if __name__ == "__main__":
    main()
```该实现将两个网格转换为浮点数组，因为 FFT 库自然地对浮点值进行操作。 马赛克使用每种颜色的随机散列进行一次编码，并且图案变成仅包含其非空单元的稀疏内核。 

在卷积之前反转内核，以便对齐与 2D 相关性的标准定义相匹配。 计算卷积后，每个有效的左上角位置对应于输出数组中的单个条目。 

由于 FFT 引入了浮点误差，因此最终的比较使用了较小容差的相等性。 正确性依赖于这样一个事实：精确匹配会产生非常稳定的目标值，而不匹配几乎总是会逐渐消失。 

## 工作示例

 考虑一个小图案和马赛克，其中图案包含一些受限单元和一些空单元。 该算法首先为颜色分配随机值，然后构建编码网格。 

| 步骤| 描述 | 关键值|
 | --- | --- | --- |
 | 1 | 从活动细胞计算出的主题哈希值 | 哈 |
 | 2 | 用随机颜色权重编码的马赛克 | 一个 |
 | 3 | 对所有比对进行卷积计算 | 转换 (i,j) |
 | 4 | 每个班次的比较| 转换 (i,j) == H |

 在有效的位置，每个受约束的主题单元都与相同的马赛克颜色对齐，因此每个贡献都完全匹配，并且卷积和等于主题散列。 

在无效的放置处，至少有一个受约束的单元格不同，这会以随机量改变聚合总和，从而破坏相等性。 

具有密集图案的第二个示例表明，空单元不会影响任何东西，因为它们从未包含在内核中，因此它们永远不会对卷积和做出贡献。

 ## 边缘情况

 一个关键的边缘情况是当主题仅包含空单元时。 在这种情况下，马赛克中的每个位置都是有效的。 该算法自然地处理这个问题，因为内核变空，到处产生零卷积，并且目标哈希也为零，因此每个位置都匹配。 

另一个边缘情况是与马赛克大小相同的图案。 卷积仅产生一个对齐，并且正确性降低为全网格比较。 该算法仍然有效，因为仅检查一个输出单元。 

几乎每个单元都处于活动状态的密集主题会强调卷积核的大小，但不会改变复杂性，因为内核最多保留$10^6$条目，并且仍然在 FFT 预处理中处理一次，而不是每次对齐。
