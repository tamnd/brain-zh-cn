 ## 解决方案
 ## 问题理解

 我们有一个小型服务器注册表，其中每个服务器都由唯一的 IP 地址标识，并且还有一个人类可读的名称。 之后，我们会得到一个配置命令列表，每个命令仅通过其 IP 引用服务器。 

任务是通过附加包含相应服务器名称的注释来丰富每个命令行。 具体来说，每当命令包含 IP 地址时，我们必须将该行替换为同一行，后跟`#name`， 在哪里`name`是IP匹配的服务器。 

输入的结构使意图非常直接：首先构建从 IP 地址到服务器名称的映射，然后使用该映射来翻译每个命令行。 

限制很小，最多 1000 个服务器和 1000 个命令。 这意味着即使是执行线性搜索的简单方法也已经在可接受的限制之内，因为每个命令对所有服务器的最坏情况扫描会给出大约 1,000,000 次比较，这在 2 秒限制下的 Python 中是微不足道的。 尽管如此，IP 查找的结构强烈建议采用基于字典的解决方案。 

一个微妙的问题是，服务器名称不能保证唯一，但 IP 地址可以。 这很重要，因为正确的查找关键字严格是 IP，而不是名称。 另一个细节是解析：IP出现在命令行中并带有尾随分号，因此在查找之前必须小心地剥离它。 

除了正确的字符串处理和映射之外，不会出现棘手的边缘情况，但粗心的解决方案可能会在某些方面失败。 一种是忘记删除结尾的分号，导致字典查找失败。 另一个问题是，如果假定有多个空格或格式变化，则会错误地分割命令。 由于格式一致，用空格分割并修剪分号就足够了。 

## 方法

 最直接的解决办法是，对于每个命令行，扫描所有已知的服务器，找到与查询的IP匹配的IP。 这是可行的，因为数据集很小，并且每次查找都是独立的。 但是，此方法对每个查询重复相同的比较。 使用 1000 个命令和 1000 个服务器，它执行多达一百万次字符串比较，这仍然可以接受但没有必要。 

关键的观察结果是 IP 和服务器名称之间的关系是静态的。 一旦我们读取了服务器列表，我们就可以预先计算一个字典，将每个 IP 字符串直接映射到它的名称。 这将每个查询减少为单个哈希表查找，而不是线性扫描。 

转换变得纯粹机械化：构建映射、解析每个命令、提取 IP、查找名称并附加它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的强力扫描 | O(纳米) | O(1) | O(1) | 已接受但没有必要 |
 | 哈希映射查找 | O(n + m) | O(n) | 已接受 |

 ## 算法演练

 我们将解决方案分为预处理和查询处理。 

1. 读取所有服务器条目并将它们存储在以 IP 地址为关键字的字典中。 每个条目将 IP 字符串直接映射到服务器名称。 这确保了以后的恒定时间检索。 
2. 迭代每个配置命令行。 每行包含一个命令字、一个 IP 和一个尾随分号。 
3. 使用空格将行拆分为标记。 第二个令牌包含带有分号的 IP。 
4. 删除 IP 令牌中的分号。 这是必要的，因为字典键存储为没有标点符号的纯 IP 字符串。 
5. 使用清理后的IP从字典中检索对应的服务器名称。 
6. 通过连接原始命令、带分号标记的原始 IP 和注释来构造输出行`#name`。 

关键的设计选择是，除了去掉分号之外，我们从不尝试重新解释或重新格式化 IP。 我们保留命令行的原始格式并仅附加注释。 

### 为什么它有效

 该字典存储从IP到名称的完整双射，并且保证每个查询IP都存在于该映射中。 每个命令行都是独立的，转换只依赖于这个固定的映射。 由于解析步骤总是提取准确的 IP 字符串（在删除`;`），查找准确无误，确保每个命令都用正确的服务器名称进行注释。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    mp = {}

    for _ in range(n):
        name, ip = input().split()
        mp[ip] = name

    out = []
    for _ in range(m):
        parts = input().split()
        command = parts[0]
        ip_with_semicolon = parts[1]

        ip = ip_with_semicolon[:-1]
        name = mp[ip]

        out.append(f"{command} {ip_with_semicolon} #{name}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```代码中的核心思想就是字典`mp`，它提供从 IP 到服务器名称的直接转换。 解析逻辑依赖于每个命令行的固定结构，因此我们安全地拆分为两个令牌，并从 IP 令牌中恰好去除一个尾随字符。 输出格式保留原始命令格式并仅附加所需的注释。 

一个常见的错误是尝试更积极地解析 IP，例如不必要地用点或分号进行分割。 这不是必需的，只会增加格式化错误的风险。

 ## 边缘情况

 一种微妙的边缘情况是多个命令引用同一 IP。 由于映射是纯粹关联的并且不被消耗或修改，因此重复查找总是返回相同的名称。 该算法自然会处理这个问题，因为字典访问不会改变状态。 

另一个潜在的陷阱是不正确的 IP 提取。 如果忘记去掉分号，查找键就会变成`192.168.0.1;`，字典中不存在。 这会导致运行时错误。 修复方法是始终删除第二个标记的最后一个字符，这保证是`;`通过输入格式。 

最后的边缘情况是假设名称是唯一的或使用它们作为键。 由于名称可能重复，因此有必要使用 IP 作为唯一密钥。 字典的设计完全避免了歧义，因为保证了IP的唯一性。
