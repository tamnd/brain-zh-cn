 ## 解决方案
 ## 问题理解

 我们被赋予了一个$n \times n$网格，其中每个单元格包含初始建筑物高度。 我们可以使用两种操作来修改网格。 我们可以雇佣一名 A 类工人进行排$i$，该行中的每个值都会增加 1，或者我们可以为列雇用 B 类型的工作人员$j$，该列中的每个值都会增加 1。每个工人最多只能使用一次，并且每个工人都有固定成本。 

在应用行操作和列操作的一些子集之后，我们希望最终的网格具有这样的属性：没有两个水平或垂直相邻的单元格具有相同的值。 目标是最小化总成本，或者确定任何操作选择都无法实现有效的网格。 

关键的结构限制是每个细胞$(i,j)$仅受是否行影响$i$是否选择以及是否列$j$被选中。 这意味着最终值具有简单的加法形式，其中每个单元格最多移动两个二元决策。 

总体而言，约束条件很严格：总计$n$所有测试用例最多为1000个，每个测试用例可以有$n$最多 1000。这立即排除了对立方或更高的依赖$n$。 检查行和列的所有子集的解决方案是不可能的，因为这将是$2^{2n}$。 甚至$O(n^3)$每个测试用例都是临界值，但只有非常小的常数才可以接受。 预期的解决方案必须将每个测试用例的问题简化为基本上线性或二次的。 

一个微妙的点是，相等约束仅在相邻单元格之间起作用。 非相邻关系是无关紧要的，这表明问题分解为网格图边缘的局部约束。 

一个幼稚的陷阱是独立处理行和列。 例如，人们可能会尝试首先修复行差异，然后贪婪地修复列差异。 这会失败，因为行选择同时影响所有列，因此一列中的本地有效修复可能会破坏另一列约束。 

另一种故障模式是假设每一行或每一列都可以根据原始网格的局部比较独立决定。 这忽略了通过共享单元耦合行和列决策的约束。 

## 方法

 蛮力的想法是尝试行和列的每个子集。 对于每个子集，计算生成的网格并检查所有邻接约束。 这是正确的，但立即不可行，因为有$2^n$行选择和$2^n$列的选择，导致指数爆炸。 

我们需要一种方法来避免考虑全局的完整分配。 关键的观察是，每一行的决策都是二元的，并且相邻单元格之间的约束仅涉及这些二元决策的差异。 

让$x_i \in \{0,1\}$表示我们是否将操作 A 应用于行$i$， 和$y_j \in \{0,1\}$表示我们是否将操作 B 应用于列$j$。 最终高度变为$$h'_{i,j} = h_{i,j} + x_i + y_j.$$现在考虑之间的水平邻接约束$(i,j)$和$(i,j+1)$。 我们需要：$$h_{i,j} + x_i + y_j \ne h_{i,j+1} + x_i + y_{j+1}.$$行项完全取消，留下：$$h_{i,j} + y_j \ne h_{i,j+1} + y_{j+1}.$$这是结构简化的关键：水平约束仅取决于列决策。 类似地，垂直约束仅取决于行决策：$$h_{i,j} + x_i \ne h_{i+1,j} + x_{i+1}.$$因此，网格分解为两个独立的一维问题：一个是行问题，一个是列问题，只是总成本是相加的。 然而，困难在于行和列分配必须同时满足它们的约束。 

每行和列在路径图上形成一个二元标记问题：相邻节点必须满足以下形式的不等式约束：$$x_i \ne x_{i+1} \text{ or } x_i = x_{i+1},$$取决于在给定任务下身高是否强制平等。 

更准确地说，对于每个相邻对，我们得出约束是否允许 (0,0)、(1,1) 或强制交替。 这成为每个节点有 2 个状态的链上的经典 DP。 

我们使用一条线上的 DP 独立解决行约束，对于列也类似。 如果其中任何一个变得不可能，那么答案就是不可能。 

最后，我们添加有效行配置和列配置的最小成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集 |$O(2^{2n} \cdot n^2)$|$O(n^2)$| 太慢了 |
 | DP 分别在行和列上 |$O(n^2)$|$O(n)$| 已接受 |

 ## 算法演练

 我们描述行的解决方案； 列是对称的。 

1. 对于每对相邻行$i$和$i+1$，我们确定哪些组合$(x_i, x_{i+1})$是有效的。 

我们逐列检查在给定的选择对下是否会发生相等。 如果任何列变得相等，则禁止该分配。 
2. 对于每个行转换，我们在四种可能性上构建一个约束掩码$(0,0), (0,1), (1,0), (1,1)$。 

这对 DP 意义上允许的转换进行编码。 
3. 我们对状态为的行运行 DP$dp[i][t]$，意味着直到行的最小成本$i$有作业$t \in \{0,1\}$。 
4. 从行过渡$i$到$i+1$仅使用允许的转换。 

如果约束禁止转换，则会跳过该转换。 
5. 国家成本$t$在行$i$是$a_i \cdot t$，因为选择行会增加成本$a_i$。 
6. 我们计算最后一行两个状态的最小值。 如果没有状态可达，则行系统是不可能的。 
7. 我们对列重复相同的过程，使用$b_j$和垂直约束。 
8. 最终答案是最优行成本和列成本之和。 

为什么分解有效是微妙的：水平约束仅依赖于列变量，垂直约束仅依赖于行变量，因此赋值的可行性完全分开。 成本也是可分离的，因此最小化分裂。 

### 为什么它有效

 每个邻接约束成为对一对二元变量的限制。 由于每个变量仅出现在沿单个维度的约束中，因此约束图分成两个独立的链。 DP 在探索所有全局一致的二进制标签时强制执行所有成对限制，确保不计算任何无效配置。 由于每个有效配置恰好对应一个 DP 路径，并且每个 DP 路径都对应一个有效配置，因此保留了最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve_line(cost, bad_pairs):
    n = len(cost)
    dp0 = 0
    dp1 = cost[0]
    
    for i in range(n - 1):
        ndp0 = ndp1 = INF
        
        for cur in [0, 1]:
            cur_dp = dp0 if cur == 0 else dp1
            if cur_dp >= INF:
                continue
            for nxt in [0, 1]:
                if bad_pairs[i][cur][nxt]:
                    continue
                val = cur_dp + (cost[i + 1] if nxt else 0)
                if nxt == 0:
                    ndp0 = min(ndp0, val)
                else:
                    ndp1 = min(ndp1, val)
        
        dp0, dp1 = ndp0, ndp1
    
    return min(dp0, dp1)

def build_row_constraints(h, n):
    bad = [[[False]*2 for _ in range(2)] for _ in range(n-1)]
    
    for i in range(n - 1):
        for x in [0, 1]:
            for y in [0, 1]:
                ok = True
                for j in range(n):
                    if h[i][j] + x == h[i+1][j] + y:
                        ok = False
                        break
                bad[i][x][y] = not ok
    return bad

def build_col_constraints(h, n):
    bad = [[[False]*2 for _ in range(2)] for _ in range(n-1)]
    
    for j in range(n - 1):
        for y in [0, 1]:
            for z in [0, 1]:
                ok = True
                for i in range(n):
                    if h[i][j] + y == h[i][j+1] + z:
                        ok = False
                        break
                bad[j][y][z] = not ok
    return bad

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        h = [list(map(int, input().split())) for _ in range(n)]
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        row_bad = build_row_constraints(h, n)
        col_bad = build_col_constraints(h, n)
        
        row_cost = solve_line(a, row_bad)
        col_cost = solve_line(b, col_bad)
        
        ans = row_cost + col_cost
        if ans >= INF:
            ans = -1
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```行 DP 和列 DP 在结构上是相同的，只是约束条件的预计算方式不同。 每个 DP 将问题视为路径上的二进制标记，其中每条边都禁止某些状态组合。 

一个微妙的实现细节是我们显式枚举每个相邻对的所有四个状态转换。 这可以避免遗漏只有一个方向有效的不对称情况。 另一个关键点是仔细初始化 dp 状态：第一行（或列）的成本要么是 0，要么是相应的招聘成本。

 ## 边缘情况

 一个重要的边缘情况是当一对相邻行中的每个单元在所有四种状态组合下变得相等时。 在这种情况下，转移矩阵变得完全禁止，并且 DP 必须正确传播不可行性。 

当只有一个分配有效时，会出现另一种边缘情况，例如强制跨行交替模式。 DP 处理这个问题是因为它显式地跟踪这两种状态并且只允许有效的转换。 

最后的边缘情况是行和列解决方案单独可行，但它们的组合效果仍然产生有效的最终约束。 由于分解是独立的，因此该算法正确地求和了最小成本，而没有耦合错误。
