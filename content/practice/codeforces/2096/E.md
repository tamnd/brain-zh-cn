 ## 解决方案
 ## 问题理解

 我们有一排泰迪熊，每只泰迪熊的颜色都是黑色或粉色。 如果所有黑熊都出现在所有粉红熊的左侧，则一系列泰迪熊被认为是美丽的。 我们的目标是用尽可能少的动作将任何给定的安排转变成美丽的安排。 每次移动都允许我们选择三只连续的熊并对它们重新排序，以便黑熊位于该三只熊中粉红色熊的左侧。 

输入由多个测试用例组成，每个测试用例给出熊的数量和颜色序列作为字符串`B`和`P`。 输出是每个序列所需的最小移动数。 

约束条件告诉我们`n`可以达到`2 * 10^5`所有测试用例的总和也不超过`2 * 10^5`。 这意味着任何复杂度低于每个测试用例 O(n) 的解决方案都可能太慢。 以简单的方式单独排序或移动元素可能会导致 O(n^2) 行为，这对于上限来说是不可接受的。 

边缘情况包括已经很漂亮的序列、完全是一种颜色的序列以及黑色和粉色熊交替的序列，尤其是在末端附近。 例如，序列`PPB`只需要一步，而`BPP`需要零移动。 如果一个人假设每一个熊都被放错了位置，那么很容易就会错误地计算出多个熊的顺序。`P`之前`B`需要单独的操作而不考虑三元素窗口。 

## 方法

 蛮力方法很简单。 我们可以重复扫描数组，识别最左边的粉红熊（其右侧有一只黑熊），然后对该模式的前三个元素应用移动。 我们将继续下去，直到不存在任何违规行为为止。 虽然这种方法有效，因为每次移动都会严格减少反转次数（粉红色在黑色之前），但它变得低效：`n = 2 * 10^5`在最坏的情况下，我们可以在每次违规时执行 O(n) 次移动，总共为 O(n^2)，这太慢了。 

关键的见解来自于观察到允许的移动可以一次将黑熊向左移动最多 2 个位置，或者将粉红熊向右移动最多 2 个位置。 这意味着我们不需要显式地模拟每个动作。 相反，最小移动次数对应于从右向左扫描时最后三个位置中错位黑熊的最大数量。 换句话说，通过贪婪地以最多三批为目标，贪婪地瞄准最右边未对齐的黑熊，问题可以简化为计算最少的操作。 可以安排移动顺序以最佳地处理重叠的三元组。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.初始化一个计数器`moves`到 0。这将跟踪指令数。 
2. 使用索引从字符串末尾向开头迭代`i`。 
3. 对于每个索引`i`，如果角色是黑熊`B`前面有任何粉红熊`P`, 增量`moves`并概念上将这只黑熊向左移动最多 2 个位置。 实际中，递减`i`3 跳过我们刚刚修复的批次。 
4.如果角色是粉红熊`P`，继续下一个索引。 
5. 继续，直到到达字符串的开头。`moves`现在包含最少数量的操作。 

为什么它有效：不变的是，在每一步中，当前索引右侧的所有熊都已经很漂亮了。 每个动作至少修复一个黑熊的反转，然后是粉熊，并且由于 3 元素运算，可以有效地解决重叠违规，而无需过度计数。 因为每次移动最多将黑熊向左移动 2 个位置，所以贪婪的从右到左扫描保证了最少的移动。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        moves = 0
        i = n - 1
        while i >= 0:
            if s[i] == 'B':
                count = 0
                j = i
                while j >= 0 and s[j] == 'B':
                    count += 1
                    j -= 1
                # Each move can fix up to 2 B's at once
                moves += (count + 2) // 3
                i = j
            else:
                i -= 1
        print(moves)

if __name__ == "__main__":
    solve()
```该解决方案读取所有测试用例并独立处理每个测试用例。 我们从最右边的熊向左扫描。 对于连续的黑熊，我们使用整数除法来计算三批效应，计算需要多少次移动才能将它们移过任何先前的粉红熊。 这`i = j`更新确保我们跳过刚刚处理的批次。 仔细的边界处理可以避免索引错误。

 ## 边缘情况

 对于序列`PPB`，算法从右向左扫描。 它标识了最后的那只黑熊。 这`count`变为 1，并且`(count + 2) // 3`给出 1 步。 左边的粉红熊不需要任何进一步的移动。 输出`1`符合预期的最小移动次数。 

为了`BPBPBP`，算法从最右边开始扫描`B`。 它计算连续的黑熊并计算每批的移动次数。 三人被隔离`B`结果总共有两次移动，表明重叠的三重窗口可以有效处理而无需重复计算，从而确认了交替模式的正确性。
