 ## 解决方案
 ## 问题理解

 我们正在使用概念乘法网格，其中行中的单元格`i`和列`j`包含值`i × j`。 我们不是明确地构建这个表，而是想象列出所有`n × m`值并按非降序对它们进行排序。 任务是找到出现在位置上的值`k`在这个排序列表中。 

关键的困难在于规模。 表的两个维度都可以高达 500,000，这使得元素总数高达 2.5 × 10^1。 任何试图生成或排序所有值的方法都是立即不可行的。 在时间限制内，甚至显式迭代所有行和列也是不可能的。 

这促使我们采取一种策略，即我们从不直接构建表，而是对值的计数进行推理。 

当存在许多重复值时，会出现微妙的边缘情况。 例如，在一个小表中`n = 3, m = 3`，值`2`出现多次。 简单的扁平化和排序方法在概念上仍然有效，但会由于内存和时间限制而失败。 另一个边缘情况是当`k = 1`，答案总是`1`，以及当`k = n × m`，其中答案是`n × m`。 任何正确的解决方案都必须自然地处理这些边界，而无需特殊的外壳。 

## 方法

 蛮力的想法很简单。 我们生产每一种产品`i × j`，将它们存储在列表中，对列表进行排序，然后返回`k`-th 元素。 这是正确的，因为它显式地构造了我们要求排序的多重集。 然而，元素的数量是`n × m`，在最坏的情况下约为 2.5 × 10^1。 即使存储 10⁷ 整数，在 Python 中也已经很紧张了； 存储 10^1 是不可能的。 排序还增加了一个对数因子，使其完全无法使用。 

关键的观察是我们实际上并不需要完整的排序列表。 我们只需要回答以下形式的查询：表中有多少条目小于或等于某个值`x`。 如果我们能够有效地计算这个计数，我们就可以对答案使用二分搜索。 

对于固定的`x`, 每行`i`贡献`min(m, x // i)`值，因为在行中`i`，所有列`j`这样`i × j ≤ x`满足`j ≤ x // i`。 对所有行求和得出元素总数 ≤`x`。 

这将问题转化为单调谓词搜索：`x`增加，值的数量 ≤`x`永远不会减少。 这种单调性允许对答案空间进行二分搜索`1`到`n × m`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nm log(nm)) | O(nm log(nm)) | O(纳米) | 太慢了 |
 | 最优（二分查找+计数） | O(n log(nm)) | O(n log(nm)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们现在使用二分搜索对答案值构建解决方案。 

1. 定义一个函数`count(x)`返回乘法表中有多少个单元格小于或等于`x`。 对于每一行`i`，最大的有效列是`x // i`，但不能超过`m`，所以我们添加`min(m, x // i)`。 
2、设置二分查找范围为`lo = 1`和`hi = n × m`。 该范围安全地包含表中所有可能的值。 
3. 反复计算`mid = (lo + hi) // 2`。 
4. 计算`count(mid)`。 如果这个值至少是`k`， 然后`mid`大到足以成为答案，所以我们移动`hi = mid`。 
5. 否则，少于`k`元素≤`mid`，所以我们需要更大的值，然后我们移动`lo = mid + 1`。 
6. 继续直到`lo == hi`。 那时，`lo`是最小值，使得至少`k`元素≤ it，这与多重集中第 k 个最小元素的定义匹配。 

每个步骤有效的关键原因是该函数`count(x)`是单调的`x`。 一旦有一个值`x`足够大至少包括`k`元素，所有较大的值也将满足此属性，因此二分搜索正确地隔离了边界。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_leq(n, m, x):
    total = 0
    for i in range(1, n + 1):
        total += min(m, x // i)
    return total

def main():
    n, m, k = map(int, input().split())

    lo, hi = 1, n * m

    while lo < hi:
        mid = (lo + hi) // 2
        if count_leq(n, m, mid) >= k:
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    main()
```核心实现细节是`count_leq`功能。 它避免构建表，而是逐行计算贡献。 每行`i`贡献一切价值`i × 1`通过`i × (x // i)`，但我们将其限制为`m`因为桌子上只有`m`列。 

二分查找保持了答案所在的不变量`[lo, hi]`。 更新规则在保持正确性的同时缩小了这个间隔。 一个常见的错误是使用`hi = mid - 1`，这打破了重复项所需的下限样式搜索； 在这里我们故意保留`hi = mid`。

 ## 边缘情况

 对于`n = 1`，表退化为单行`[1, 2, ..., m]`。 该算法简化为二分查找最小的`x`这样`x ≥ k`， 自从`count(x)`恰好变成`min(m, x)`。 计数函数自然地处理这个问题，因为只有行`i = 1`做出贡献。 

为了`k = 1`，二分查找立即收敛到`1`因为`count(1)`总是至少为 1。不需要特殊逻辑。 

为了`k = n × m`，搜索推向最大的产品`n × m`。 在`x = n × m`，每个条目都被计数，并且谓词变为真，正确地确定了上限。 

对于高度不平衡的表，例如`n = 1`和大`m`，反之亦然，循环仍然运行在所有行上，但每次检查保持线性，并且二分搜索确保此扫描仅以对数重复。
