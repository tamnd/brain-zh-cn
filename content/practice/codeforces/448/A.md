 ## 解决方案
 ## 问题理解

 我们有固定数量的架子和一系列奖励，分为两类：杯子和奖牌。 每个类别进一步分为三个等级，但对于放置逻辑来说，这些等级除了计算每个类别中的总项目外并不重要。 

每个架子都有两个结构限制。 它只能存储一种类别，这意味着奖杯和奖牌不能混合放在同一个架子上。 此外，架子的容量限制取决于类别：每个架子最多 5 个杯子，每个架子最多 10 个奖牌。 

任务是确定是否可以将所有物品分布在给定数量的货架上，同时遵守这些约束。 

关键的抽象是，我们不是按顺序排列单个项目，而是将数量打包到具有固定每个容器容量的容器中，其中容器按类型分为两个独立的组。 

限制很小。 所有计数最多为 100，架子数量也最多为 100。这排除了对配置进行搜索或回溯的任何需要。 任何对货架上的物品进行指数分配都将远远超出必要的范围，尽管在这种规模上它在计算上仍然是可行的。 

一个天真的但可能的错误是尝试贪婪地分配项目而不仔细尊重容量分组。 

一种错误的方法是独立分发奖杯和奖牌，而不确保所使用的架子总数不超过 n。 例如，如果杯子需要 3 个架子，而奖牌需要 4 个架子，但相同的架子被错误地认为是可重复使用的，那么天真的实现可能会错误地合并它们并产生错误的“是”。 

另一种微妙的边缘情况是当一个类别为空时。 例如，如果只有杯子，则答案纯粹取决于 ceil(total_cups / 5) 是否适合 n，并且奖牌约束不得人为地消耗货架。 

## 方法

 强力解释将模拟将每个单独的物品分配到货架的所有可能的方式，尊重容量限制并确保不混合类型。 每个项目最多有 n 个选择，总共有 600 个项目，因此这很快就会变成具有天文数字般巨大的状态空间的组合。 即使进行修剪，这也是不必要的，因为问题的结构不依赖于排序或单独的分配选择。 

关键的观察是，在每个类别中，只有总数才重要。 由于每个架子可以容纳单一类型的固定最大数量的物品，因此杯子所需的最小架子数量完全取决于我们需要多少个完整的 5 组，同样，奖牌需要 10 组。一旦我们分别计算出杯子和奖牌需要多少个架子，剩下的唯一问题是所需架子的总和是否适合 n。 

这种减少之所以有效，是因为不同类型之间不共享货架。 一旦一个架子被分配给杯子，它就会被杯子完全消耗，对于奖牌也是如此。 除了货架总数的竞争之外，不存在任何耦合。 

因此，问题变成了简单的打包计算，然后进行可行性检查。

 ## 算法演练

1. 通过对所有三种杯子类型求和来计算杯子总数。 由于货架约束不区分等级，因此这将问题分解为单个数量。 
2. 计算杯子所需的架子数量，即total_cups 的上限除以5。每个架子最多可容纳5 个杯子，因此这表示所需的最少架子数量。 
3. 通过对所有奖牌类型求和来类似地计算奖牌总数。 
4. 奖牌所需的架子数量为total_medals 的上限除以10。每个架子最多可容纳10 个奖牌。 
5. 添加两个所需的货架数量。 这表示如果我们在各自的限制内最佳地分配杯子和奖牌，则消耗的货架总数。 
6. 将此总和与 n 进行比较。 如果小于或等于n，则输出YES，否则输出NO。 

### 为什么它有效

 每个货架都属于一个类别，因此问题分解为两个独立的装箱问题。 在每个类别中，除了可能有一个部分填充的货架之外，每个货架都被最佳地填充，并且除了最大化每个货架的使用之外，在货架上重新排列物品没有任何好处。 因此，计算出的上限值是精确的下限和可实现的上限结构，这意味着它们的总和是所需货架的精确最小数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a1, a2, a3 = map(int, input().split())
    b1, b2, b3 = map(int, input().split())
    n = int(input())

    cups = a1 + a2 + a3
    medals = b1 + b2 + b3

    cup_shelves = (cups + 4) // 5
    medal_shelves = (medals + 9) // 10

    print("YES" if cup_shelves + medal_shelves <= n else "NO")

if __name__ == "__main__":
    solve()
```该解决方案首先按类型聚合所有项目，忽略内部分类，因为它对容量约束没有影响。 上限除法是使用整数算术实现的：除以 5 之前加 4 可确保杯赛的正确舍入，而奖牌除以 10 之前加 9 也能确保正确舍入。 

最终比较直接检查现有货架的可行性。 

一个常见的错误是忘记货架不能混合类型。 另一种尝试是贪婪地分配物品，却没有认识到每种类型的最佳包装总是装满的，可能除了一个架子之外。

 ## 边缘情况

 一个关键的边缘情况是当一个类别为空时。 假设杯子为零：

 输入：```
0 0 0
10 0 0
1
```杯子架为0，奖牌架为1，总数为1，因此输出为YES。 该算法自然地处理了这个问题，因为零的上限除法仍然为零，并且没有浪费任何人工架子。 

另一个边缘情况是两个类别独立拟合但加起来超过 n。 例如：

 输入：```
5 0 0
10 0 0
1
```杯子架为1个，奖牌架为1个，总数为2个，因此输出为NO。 一个幼稚的错误是试图将奖牌放入杯架的剩余空间中，但由于严格的分离规则，这是无效的。 该算法通过设计强制执行这种分离，因此它正确地拒绝了这种情况。
