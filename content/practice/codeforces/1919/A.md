 ## 解决方案
 ## 问题理解

 爱丽丝和鲍勃各自拥有一个包含一定数量硬币的钱包。 在每个回合中，当前玩家可以保持钱包不变，也可以交换两个钱包。 在做出选择之后，他们必须从当前持有的钱包中取出一枚硬币。 

仅当玩家最终持有的钱包在取出硬币之前至少包含一枚硬币时，该举动才是合法的。 第一个不能做出合法动作的玩家就输了。 

对于每个测试用例，我们都会得到初始硬币数量`a`和`b`。 两个玩家都玩得很完美，我们必须确定获胜者是先行动的爱丽丝，还是鲍勃。 

限制大得惊人。 每个钱包最多可包含`10^9`硬币，最多可达`1000`测试用例。 任何逐步模拟游戏的方法都是不可能的。 单场比赛大约可以持续`a + b`转弯，这可能是关于`2 · 10^9`移动。 我们需要对获胜和失败位置进行直接的数学描述。 

棘手的部分是，交换钱包的能力使游戏看起来比简单的消除桩游戏更复杂。 一个常见的错误是关注哪个玩家拥有哪个钱包。 所有权不断变化，实际上是无关紧要的。 另一个错误是认为钱包越大总是更重要。 小例子表明，只有硬币总数才能最终决定获胜者。 

考虑一下立场：```
a = 1, b = 1
```硬币总数为 2 个。Alice 取出一枚硬币，Bob 取出一枚硬币，然后就没有硬币了。 爱丽丝是下一个玩家，她输了。 正确答案是`Bob`。 

现在考虑：```
a = 1, b = 4
```硬币总数为 5 个。由于总共有 5 个可移动硬币，因此游戏正好持续 5 步。 Alice 进行了第 1、3 和 5 步操作，因此 Bob 之后无法移动。 正确答案是`Alice`。 

尝试追踪钱包所有权的粗心方法可能会错过这个简单得多的模式。 

## 方法

 最直接的想法是将游戏状态建模为`(a, b, turn)`并递归判断每个位置是赢还是输。 在每个状态下，当前玩家最多有两个选择：交换或不交换。 选择后，一枚硬币将从当前钱包中移除。 

对于很小的值，这有效。 我们可以枚举所有可到达的位置并观察博弈树。 问题是状态空间随着钱包的大小而增长。 自从`a`和`b`可能大到`10^9`，这样的搜索是完全不可行的。 

要找到模式，请检查移动过程中实际发生的变化。 

每一个合法的举动都会从游戏中删除一枚硬币。 任何举动都不会创造硬币。 交换只会改变当前持有哪个钱包的人。 每回合硬币总数正好减少一枚。 

让```
S = a + b
```最初有`S`总共硬币。 由于每次移动恰好移除一枚硬币，因此可以精确地`S`在所有硬币消失之前移动。 

关键的观察是，只要某个地方至少存在一枚硬币，当前玩家就总是可以采取行动。 如果他们当前的钱包是空的，他们只需交换并拿走非空的钱包。 唯一不可能进行转移的情况是两个钱包中的硬币都为零时。 

这意味着游戏长度是完全固定的。 正是`S`行动，无论策略如何。 

一旦长度固定，游戏就变得微不足道了。 爱丽丝的动作已编号```
1, 3, 5, ...
```鲍勃做出了编号的动作```
2, 4, 6, ...
```如果`S`奇数，Alice 执行最后一步，Bob 面对空位。 爱丽丝赢了。 

如果`S`为偶数时，Bob 执行最后一步，Alice 面对空位。 鲍勃赢了。 

整个游戏简化为检查奇偶性`a + b`。

 ## 算法演练

 1. 阅读`a`和`b`。 
2. 计算硬币总数：```
S = a + b
```每一步都会消除一枚硬币，所以`S`也是游戏中的确切步数。 
3. 检查是否`S`是奇数还是偶数。 

如果`S`奇怪的是，爱丽丝做出了最后一步并获胜。 

如果`S`势均力敌，鲍勃做出最后一步并获胜。 
4.输出对应的获胜者。 

### 为什么它有效

 关键的不变量是，每一次合法的移动都会使硬币总数恰好减少一个。 任何举动都无法改变这一点。 此外，每当至少有一枚硬币留在某处时，当前玩家可以通过必要时交换来获得一个非空钱包。 因此，游戏永远不会提前结束。 

比赛必须继续进行，直到所有`a + b`硬币已被移除。 由于总移动次数是固定的并且等于`a + b`，获胜者仅由该数字的奇偶性决定。 奇数步意味着 Alice 采取最后一步，而偶数意味着 Bob 采取最后一步。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    a, b = map(int, input().split())
    if (a + b) % 2:
        print("Alice")
    else:
        print("Bob")
```实现直接遵循数学特征。 

对于每个测试用例，我们计算`a + b`并检查其奇偶性。 不需要模拟，因为策略不影响游戏长度。 每一步总是消耗一枚硬币，并且游戏总是持续到所有硬币都消失为止。 

Python 中不存在溢出问题。 即使是最大可能的总和，```
10^9 + 10^9 = 2 · 10^9
```适合正常的整数算术。 

唯一微妙的一点是认识到交换永远不会改变未来移动的总数。 一旦做出这一观察，实施就变成了一项单行决策。
