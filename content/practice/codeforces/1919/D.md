 ## 问题理解

 我们得到了二叉树从根到叶子的距离，以 DFS 叶子顺序列出。 

每个内部顶点都有两个子顶点。 一条出边具有权重`0`另一个有重量`1`。 树的实际形状未知，只知道叶子距离。 

任务是确定这样的树是否可以生成给定的数组。 

所有测试用例的叶子总数最多为`2 · 10^5`，所以任何二次解`n`立即被排除。 甚至`O(n√n)`会不舒服。 我们需要一些接近线性或`O(n log n)`。 

棘手的部分是 DFS 顺序强加了一个强大的结构。 属于同一子树的叶子占据一个连续的段。 幼稚的重建尝试很容易做出局部有效的选择，而这些选择后来就变得不可能了。 

一种重要的边缘情况是最小值。 

输入：```
2
0 0
```输出：```
NO
```两片叶子不能同时有距离`0`。 每对兄弟姐妹都相差一个，因为一个子边缘具有权重`0`另一个有重量`1`。 根本身对应于单个距离`0`，因此有效数组必须恰好包含一个零。 

另一个微妙的情况是：```
3
0 2 1
```输出：```
NO
```价值`2`需要一些最终可以作为其父距离的相邻结构`1`。 虽然一个`1`存在于数组中，DFS 排序会阻止它被正确使用。 

第三个容易被忽略的例子是：```
3
0 1 2
```输出：```
YES
```这些值单调增加，但这仍然是可以实现的。 仅查看相邻元素是不够的。 我们需要推理递归合并后剩下的最接近的较小值。 

## 方法

 蛮力视图是反转树的构造。 

如果两个叶子是兄弟姐妹，那么它们的距离正好相差一。 当我们将它们合并到其父级中时，父级的距离将变为两个值中较小的一个。 我们可以重复搜索有效的相邻对，将其合并，然后继续，直到剩下一个值。 

这准确地反映了树结构，因此它是正确的。 问题是可以有很多选择。 探索所有合并顺序是指数级的。 即使贪婪地模拟合并与昂贵的更新也会很快变得二次。 

关键的观察是我们实际上不需要执行合并。 

考虑一个值`x > 0`。 在反向过程中的某个地方，它必须与有价值的节点配对`x - 1`。 在目前的DFS订单中，合作伙伴必须出现在其一侧。 如果我们在左边和右边寻找最接近的严格较小的值，那么它们中至少有一个必须等​​于`x - 1`。 否则无法创建该叶子所需的父叶子。 

这就把树问题变成了数组问题。 

对于每个职位`i`：

- 如果`a[i] = 0`，它是唯一的根距叶子。 
- 如果`a[i] > 0`，那么在左边和右边最接近的严格较小的值中，至少有一个必须恰好是`a[i] - 1`。 

可以使用单调堆栈在线性时间内计算最近的较小元素。 

结果是`O(n)`检查每个测试用例。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力合并模拟| 指数或 O(n²) 取决于实现 | O(n) | 太慢了 |
 | 单调堆栈验证 | O(n) | O(n) | 已接受 |
