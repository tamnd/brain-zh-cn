 ## 解决方案
 ## 问题理解

 给定一个数组，我们必须将其分成两个子序列，称它们为$s$和$t$，精确地覆盖每个元素一次，同时保留每个子序列内的相对顺序。 

对于任何序列，惩罚是从左向右移动时序列增加的次数。 所以每次$b_i < b_{i+1}$，我们支付一个单位。 

目标是将元素分配到两个子序列中，以使两个序列内增加的相邻对的总数最小化。 

约束允许最多$2 \cdot 10^5$总元素，因此每个测试用例的任何解决方案都必须基本上是线性或接近线性的。 所有分割上的二次 DP 或显式跟踪所有子序列是不可能的。 

一个关键的边缘情况是数组已经不增加或恒定。 在这些情况下，最佳答案是零，因为我们可以将所有内容放入一个子序列中并且永远不会增加。 另一个边缘情况是严格递增的数组，其中任何子序列仍将继承递增的结构，除非仔细拆分，因此成本变得不平凡并强制贪婪分配。 

## 方法

 如果我们尝试蛮力，我们将每个元素分配给$s$或者$t$，然后计算罚分。 那是$2^n$每个测试用例的分配，这立即是不可能的。 

更结构化的观点是从左到右处理元素并决定将每个元素放入哪个子序列。 惩罚仅取决于子序列中的最后一个元素是否小于当前元素，因此每个子序列的行为就像一个链，其中增加是“不良转换”。 

关键的观察是，每个子序列实际上都是一个结构，我们希望避免创建增加的相邻对。 因此每个子序列的行为应该像一个“尽可能递减”的序列。 

这就引出了经典的贪心思想：维护两个子序列的最后一个值，并始终将当前元素分配给导致新惩罚增加最少的子序列。 

在每一步中，只有两个状态很重要，因此问题会崩溃为一个具有不断转换的小型 DP 式贪婪问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n)$|$O(n)$| 太慢了 |
 | 两种状态的贪婪赋值 |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们维护两个代表子序列最后一个元素的变量$s$和后续$t$。 我们还跟踪累计罚款。 

我们从左到右处理元素并决定将每个值放置在哪里。 

### 步骤

 1. 将两个子序列初始化为空，这意味着它们的最后一个元素被设置为$+\infty$（所以第一个元素永远不会产生惩罚）。 

这确保了第一次任务始终是免费的。 
2. 对于每个元素$x$，计算将其附加到的成本$s$并到$t$。 

如果该子序列的最后一个元素严格小于$x$，否则为 0。 
3. 选择成本增加较小的子序列。 如果两者相等，则任意选择。 
4. 将所选子序列的最后一个元素更新为$x$并将成本添加到答案中。 

### 为什么它有效

 创建惩罚的唯一方法是在本地将元素放置在同一子序列中较小的前一个元素之后。 任何未来的决定都不会追溯性地改变这种增加是否已经发生。 这使得除了两个子序列的最后一个值之外，每个步骤的成本都是独立的。 因此，最小化立即惩罚的贪婪选择是全局最优的，因为延迟或将增加转移到未来不会减少增加邻接的总数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    INF = 10**18

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        last_s = INF
        last_t = INF
        ans = 0

        for x in a:
            cost_s = 1 if last_s < x else 0
            cost_t = 1 if last_t < x else 0

            if cost_s <= cost_t:
                ans += cost_s
                last_s = x
            else:
                ans += cost_t
                last_t = x

        print(ans)

if __name__ == "__main__":
    solve()
```该实现直接模拟贪心赋值。 唯一微妙的细节是将最后一个值初始化为一个非常大的数字，以便第一个元素永远不会产生惩罚。 决策规则必须一致：安全地打破第一个子序列的平局，但任何平局打破都有效，因为除了交换对称状态之外，它不会影响未来的成本结构。

 ## 边缘情况

 一种重要的边缘情况是值上下交替。 在这种情况下，贪婪分配可确保每次上升被“吸收”至最多一个子序列，从而防止重复惩罚。 另一个是当出现许多相等的值时，两个子序列都不会产生成本，从而确认相等不会影响惩罚的形成。
