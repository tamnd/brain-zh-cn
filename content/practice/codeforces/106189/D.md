 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，可以删除任何元素，同时保留剩余元素的顺序。 

目标是保留尽可能多的元素，以便在生成的子序列中每个内部元素都是严格的峰或严格的谷。 对于子序列内的每个位置，其值必须大于两个邻居或小于两个邻居。 换句话说，连续元素之间的差异必须在符号上交替。 

输出不是子序列本身。 我们必须打印原始数组中所选元素的索引。 如果不存在长度至少为 3 的振荡子序列，我们打印`0`。 

数组长度可以达到50000。 在最坏的情况下，二次动态规划解决方案将需要大约 25 亿次比较，这远远超出了可用时间。 周围的一切`O(n²)`立即被排除。 线性或`O(n log n)`需要解决方案。 

棘手的情况来自于相等的值和长时间的单调运行。 

考虑：```
3
1 1 2
```正确答案是`0`。 仅检查增加与减少的粗心实现可能会错误地将前两个值视为有效的方向变化。 

考虑：```
5
1 2 3 4 5
```每个子序列都是单调的。 不存在长度至少为 3 的振荡，所以答案是`0`。 

考虑：```
5
1 5 3 4 2
```整个序列已经交替：```
1 < 5 > 3 < 4 > 2
```答案包含所有五个指数。 

考虑：```
6
1 4 7 5 2 6
```价值观`4`和`5`两者都不需要。 最长的振荡子序列仅保留转折点：```
1 < 7 > 2 < 6
```保留每次价值变化的幼稚策略不会产生有效的振荡。 

## 方法

 暴力破解的思想是动态规划。 

对于每个位置和每个先前的位置，我们可以尝试扩展子序列，同时记住最后一步是增加还是减少。 这正确地找到了最长的振荡子序列，但它需要检查所有索引对。 和`n = 50,000`，最坏情况的工作量约为`50,000²`，这是完全不可行的。 

关键的观察是，在严格递增的运行中，只有最后一个元素很重要。 假设我们目前有：```
... < 3 < 5 < 8
```如果我们想要未来减少，保持`8`总是至少和保持一样好`5`或者`3`， 因为`8`为下一步的下行提供了更多的自由。 

同样的推理也适用于减少运行。 里面```
... > 10 > 7 > 4
```只有最小的端点才有用。 

这意味着每个单调段都可以被压缩到其端点。 幸存下来的元素正是转折点、高峰和低谷。 贪心算法可以在线维护它。 

我们从左到右构建答案索引。 

每当最后三个考虑的值是单调的时：```
x ≤ y ≤ z
```或者```
x ≥ y ≥ z
```中间值`y`永远不可能是最佳振荡子序列中的峰值或谷值。 我们将其删除并保留更极端的端点。 

处理整个数组后，剩余索引形成最大长度振荡子序列。 这与经典摆动子序列问题中使用的贪婪原理相同。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力DP | O(n²) | O(n²) 或 O(n) | 太慢了|
 | 贪婪的转折点| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.以索引开始答案列表`0`。 
2. 从左到右处理索引。 
3. 对于当前索引`i`，检查最后两个选定的索引并`i`。 
4. 让他们的价值观成为`x`,`y`， 和`z`。 
5.如果`x ≤ y ≤ z`， 然后`y`位于非递减段内。 消除`y`并将其替换为`i`。 
6.如果`x ≥ y ≥ z`， 然后`y`位于非增加段内。 消除`y`并将其替换为`i`。 
7. 否则，方向将在`y`和`z`。 重点`y`变成峰或谷，所以附加`i`。 
8.处理完所有索引后，所存储的索引描述了最长的振荡子序列。 
9. 如果剩余索引少于三个，则打印`0`。 否则打印长度和索引。 

### 为什么它有效

 不变的是，在处理数组的任何前缀之后，存储的索引形成在该前缀内结束的最长可能的振荡子序列。 

每当三个连续的候选值满足```
x ≤ y ≤ z
```中间值从来没有用。 任何可以跟随的未来元素`y`也可以关注`z`， 和`z`至少同样极端。 更换`y`和`z`不能减少可实现的最大摆动长度。 

同样的论点也适用于```
x ≥ y ≥ z
```其中最新值至少与中间值一样有用。 

结果，每个被删除的元素都被证明是多余的。 每个保留的内部元素都对应于真正的方向变化，使其成为峰或谷。 由于仅丢弃冗余点，因此所得子序列具有最大可能长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

ans = [0]

for i in range(1, n):
    while len(ans) >= 2:
        x = a[ans[-2]]
        y = a[ans[-1]]
        z = a[i]

        if (x <= y <= z) or (x >= y >= z):
            ans.pop()
        else:
            break

    ans.append(i)

if len(ans) < 3:
    print(0)
else:
    print(len(ans))
    print(*ans)
```名单`ans`存储索引，而不是值，因为问题要求原始序列中的位置。 

这`while`循环是贪婪策略的核心。 如果最新值继续当前的单调趋势，则先前的端点不再有用并被删除。 

使用`while`而不是单个`if`很重要。 删除一个索引后，形成一个新的三元组，并且也可能是单调的。 该过程持续进行，直到最后选择的点成为真正的转折点或仅保留一个先前的点。 

条件自然会处理相等的值```
x <= y <= z
x >= y >= z
```这可以防止平坦部分产生假振荡。 

每个索引插入一次，最多删除一次，因此总运行时间保持线性。

# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))

    ans = [0]

    for i in range(1, n):
        while len(ans) >= 2:
            x = a[ans[-2]]
            y = a[ans[-1]]
            z = a[i]

            if (x <= y <= z) or (x >= y >= z):
                ans.pop()
            else:
                break

        ans.append(i)

    out = []

    if len(ans) < 3:
        out.append("0")
    else:
        out.append(str(len(ans)))
        out.append(" ".join(map(str, ans)))

    return "\n".join(out)

# sample-like cases
assert run("3\n1 3 2\n") == "3\n0 1 2"
assert run("3\n1 2 3\n") == "0"

# minimum size
assert run("1\n5\n") == "0"

# all equal
assert run("5\n7 7 7 7 7\n") == "0"

# already oscillating
assert run("5\n1 5 2 6 3\n") == "5\n0 1 2 3 4"

# long monotone run compressed to endpoints
assert run("6\n1 4 7 5 2 6\n") == "4\n0 2 4 5"

 ## 边缘情况

 考虑：```
3
1 1 2
```加工`2`创建模式：```
1 ≤ 1 ≤ 2
```中间索引被删除。 最终索引集变为：```
[0, 2]
```它的长度只有二，所以算法打印`0`。 相等的值绝不会产生虚假的峰值或谷值。 

考虑：```
3
1 2 3
```该模式始终在增加：```
1 ≤ 2 ≤ 3
```中间点被丢弃，只保留端点。 最终的长度还是二，所以答案是`0`。 

考虑：```
6
5 4 3 2 1 0
```每个新值都继续相同的下降趋势。 该算法反复删除前一个端点并保留最新的端点。 最终子序列仅包含第一个和最后一个索引，这是正确的，因为不存在长度至少为 3 的振荡。 

考虑：```
5
1 3 2 4 1
```每个内部元素都已经是严格的峰或谷：```
1 < 3 > 2 < 4 > 1
```没有任何单调性条件触发，所有索引都保留，并且算法返回完整序列。
