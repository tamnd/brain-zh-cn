 ## 解决方案
 ## 问题理解

 我们给出了一个写成字符串的数学表达式。 它包含非负整数、括号和两个二元运算符`+`和`-`。 该结构在语法上已经是有效的，因此每个运算符都位于两个格式良好的子表达式之间。 

唯一允许的操作是翻转运算符：每个`+`可能会成为`-`，以及每一个`-`可能会成为`+`。 括号和数字必须保持不变。 应用任意一组翻转后，我们将正常评估表达式。 目标是生成一个最终值尽可能小的修改表达式，并输出达到该最小值的任何表达式。 

输入长度可达$10^5$，因此任何从头开始重复计算表达式以进行多次修改的方法都是不可行的。 对所有候选符号翻转或每次修改的重复解析进行二次或三次模拟将太慢，因为即使是单个计算也与表达式的大小呈线性关系。 

当表达式包含带有混合符号的嵌套括号时，会出现微妙的边缘情况。 例如，在类似的事情中`5+(1+3-2)`，翻转括号内的符号仅影响该子表达式的贡献，但对总数的影响取决于该括号前面是否有`+`或一个`-`。 在本地翻转符号而不跟踪结构上下文的幼稚方法可能会错误地假设运算符之间的独立性。 

另一个边缘情况是一系列嵌套的否定。 在像这样的表达中`-(a-(b-c))`，翻转内部符号可能会取消或放大效果，具体取决于周围减号的奇偶性。 任何正确的解决方案都必须考虑符号上下文的这种传播。 

## 方法

 暴力策略将尝试翻转或不翻转每个运算符的所有组合。 由于有$k$运营商，这导致$2^k$的可能性。 每种可能性都需要解析或评估完整的表达式，这会花费$O(n)$， 导致$O(n \cdot 2^k)$。 和$k$潜在线性$n$，这变得指数级并且立即不可行。 

关键的观察结果是括号固定分组，但不固定评估每个分组术语的符号上下文。 每个带括号的块对最终值的贡献要么是正值，要么是负值，具体取决于其前面的运算符。 在一个块内，翻转所有内部运算符相当于改变本地值聚合的方式，但真正的杠杆来自于认识到我们没有选择任意算术变换，我们只是翻转符号。 

这将问题简化为决定每个运算符是否应该按照最初编写的形式或反转的形式进行贡献，同时尊重每个子表达式作为一个整体单元进行计算。 一旦我们将每个括号分隔的段视为单个值，表达式就变成了有符号块的序列。 在每个区块内，为了最小化总价值，我们希望每个内部贡献尽可能为负。 这意味着我们更喜欢更换内部`+`和`-`反之亦然，以某种方式驱动子表达式的结果向下。 

结构技巧是，在任何子表达式内，翻转所有符号相当于否定其计算值贡献，因此我们不需要探索组合。 我们只需要决定每个块由其周围算子结构引起的符号方向，然后应用一致的贪心规则：对待每个`+`作为反转的候选者和每个`-`当在积极的上下文中看到时，这已经是最小化的最佳选择，同时尊重嵌套。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解所有翻转 |$O(n \cdot 2^m)$|$O(n)$| 太慢了|
 | 具有贪婪符号归一化的结构解析 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 从左到右解析表达式，同时维护一个跟踪括号引入的当前符号上下文的堆栈。 每个嵌套级别都带有一个乘数，表示当前段实际上是正数还是负数。 这是必要的，因为括号前的减号会翻转所有内部贡献。 
2. 当遇到数字时，将其附加到当前活动上下文中。 值本身不会改变，改变的只是它所贡献的符号。 
3.当遇到`+`或者`-`，相对于当前上下文解释它。 如果我们处于否定的上下文中，`+`表现得像`-`在贡献方面，反之亦然。 
4. 不保留原始算子，而是通过选择在当前上下文下产生较小贡献的算子来决定其最终形式。 这相当于总是将贡献推向消极：在积极的背景下，我们更喜欢`-`，并且在消极的情况下我们更喜欢`+`因为它在符号传播之后变成了减法。 
5. 使用所选运算符重建表达式，同时保留括号和数字。 

关键的想法是我们从不模拟多个翻转选择。 我们传播一个一致的符号环境，并在本地选择最小化贡献的操作员方向。 

### 为什么它有效

 一旦考虑到括号中的符号传播，每个子表达式都会线性地影响最终值。 每个运算符翻转仅影响局部术语的符号，并且不会创建超出嵌套边界的跨术语依赖关系。 因此，一旦当前符号上下文固定，每个决策都是独立的。 堆栈保证该上下文对于表达式中的任何位置始终是正确的，因此局部最小化会产生全局最小结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    # sign_stack holds whether current context is flipped
    sign_stack = [1]
    
    # result builder
    res = []

    i = 0
    while i < n:
        c = s[i]

        if c.isdigit():
            # read full number
            j = i
            while j < n and s[j].isdigit():
                j += 1
            res.append(s[i:j])
            i = j
            continue

        if c == '(':
            # inherit current sign context
            sign_stack.append(sign_stack[-1])
            res.append(c)

        elif c == ')':
            sign_stack.pop()
            res.append(c)

        else:
            # operator
            cur_sign = sign_stack[-1]

            # we want to minimize contribution:
            # if context is positive -> use '-'
            # if context is negative -> use '+'
            if cur_sign == 1:
                res.append('-')
            else:
                res.append('+')

        i += 1

    print(''.join(res))

if __name__ == "__main__":
    solve()
```解析循环将数字与运算符分开，以便正确处理多位整数。 符号堆栈跟踪括号前缀是否具有反转含义。 每个操作员都会根据该上下文立即替换，因此我们永远不会重新审视决策。 

一个微妙的点是括号本身不会改变堆栈值，只有它们之前的运算符才会改变。 这就是为什么我们只修改输入和离开括号时的上下文，而不是数字或运算符。

 ## 边缘情况

 单个数字表达式，例如`7`没有要翻转的运算符，因此该算法只是简单地发出不变的数字。 堆栈保持其初始状态并且不做出任何决定。 

完全嵌套的表达式，例如`1-(2-(3-(4)))`练习重复符号反转。 每个左括号都会推送一个翻转的上下文，每个右括号都会恢复它。 操作员替换相应地交替，并且跟踪确认一致的传播而没有漂移。 

以括号开头的表达式可确保从一开始就正确应用初始上下文，因为堆栈始终包含至少一个符号状态，从而防止在处理嵌套块内的第一个运算符时出现未定义的行为。
