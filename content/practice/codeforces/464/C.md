 **求解时间：** 1m 15s

 ## 解决方案
 ## 问题理解

 我们从一个十进制字符串开始`s`。 然后按顺序应用一系列替换规则。 每个规则都有以下形式`d -> t`，表示每次出现的数字`d`被字符串替换`t`。 

一个关键细节是，不会一次对当前字符串执行一个字符的替换。 每个规则都会转换整个当前字符串。 由于后面的规则可能会重新定义出现在较早替换字符串中的数字，因此数字的最终扩展取决于它后面的所有规则。 

应用所有替换后，结果字符串将被解释为十进制数，我们必须计算其值模`10^9 + 7`。 前导零仍然是字符串表示形式的一部分，但它们不会影响数值。 

这些约束立即排除了对最终字符串的任何模拟。 原始字符串的长度可达`10^5`，并且最多可以有`10^5`更换规则。 虽然所有右边的总长度只有`10^5`，重复替换可能会使概念上的最终字符串变得非常大。 单个数字可能会扩展为一个长字符串，该字符串的数字会再次扩展，依此类推。 实际结果很容易包含指数级数量的字符。 

这意味着我们绝不能构建最终的字符串。 我们需要一个压缩表示，允许我们计算结果数模`10^9 + 7`。 

一些边缘情况很容易被错误处理。 

考虑：```
s = "3"
rule: 3->
```最后的字符串是空的。 该问题将结果数定义为`0`。 任何假设每次替换都至少产生一位数字的方法在这里都会失败。 

考虑：```
s = "2"
rules:
2->00
```最终的字符串是`"00"`。 从数字上看，这仍然是`0`。 该算法必须分别处理字符串长度和模值，而不是尝试去除前导零。 

考虑：```
s = "1"
rules:
1->23
2->4
```最终正确的结果是`"43"`， 不是`"23"`。 第二条规则影响数字`2`由第一条规则引入。 规则之间的这种依赖性是问题的核心难点。 

## 方法

 蛮力的想法很简单。 维护当前字符串并逐字应用每个替换。 对于等于目标数字的每个字符，附加替换字符串。 

这是正确的，因为它完全遵循问题陈述。 问题是规模增长。 即使是很小的链条，例如```
1->11
```重复多次，每一步的长度都会加倍。 最终的字符串可能会变得指数级大，远远超出内存限制。 

关键的观察是我们不需要最终的字符串本身。 计算十进制数模数`M`，一个字符串只提供两条信息：

 1.它的长度。 
2. 其数值模`M`。 

假设一个字符串`A`有价值`val(A)`和长度`len(A)`，和一个字符串`B`有价值`val(B)`和长度`len(B)`。 

对于串联`AB`：$$val(AB)=val(A)\cdot 10^{len(B)}+val(B)$$模数`M`。 

这意味着每个扩展数字都可以由一对表示：$$(value,\ length)$$而不存储实际的字符串。 

现在看看替换规则。 数字的含义取决于未来的规则，而不是过去的规则。 这表明向后处理规则。 

想象一下，在应用所有后面的规则后，我们已经知道每个数字的最终扩展。 那么对于一个规则```
d -> t
```我们可以计算出最终的展开式`d`通过连接内部数字的已知扩展`t`。 

从最后一条规则到第一条规则的处理正是这种情况。 

最初，在处理任何规则之前，每个数字都会扩展为自身。 然后，每向后一步都会使用右侧出现的数字的当前扩展来更新一位数字。 

处理完所有规则后，我们就知道原始字符串中每个数字的最终扩展。 最终扫描`s`计算答案。

 | 最佳 | O( | s | + 总替换长度) |

 ## 算法演练

 1.让`MOD = 10^9 + 7`。 
2. 预先计算十模的幂`MOD`达到最大可能的扩展长度贡献。 由于所有替换字符串的总长度最多为`10^5`，达到该范围的计算能力就足够了。 
3. 对于每个数字`0...9`， 维持：`val[d]`= 最终展开模的值`MOD`。`len[d]`= 最终展开模的长度`MOD-1`。 
4. 初始化每个数字以代表其自身：`val[d] = d`

`len[d] = 1`5. 阅读所有规则并保存。 
6. 从最后到第一个处理规则。 
7. 对于规则`d -> t`，建立扩展`d`通过扫描`t`从左到右。 
8. 维护两个变量：`cur_val`

`cur_len`最初两者都为零。 
9. 对于每个数字`x`在`t`，连接已经计算的扩展`x`：$$cur\_val = cur\_val \cdot 10^{len[x]} + val[x] \pmod{MOD}$$

$$cur\_len = cur\_len + len[x] \pmod{MOD-1}$$1. 处理完整个右侧后，分配：$$val[d] = cur\_val$$

$$len[d] = cur\_len$$1.处理完所有规则后，处理原始字符串`s`。 
2. 从零开始，将每个数字的最终扩展连接起来`s`使用相同的公式。 
3. 输出结果取模后的值`MOD`。 

长度以模数存储的原因`MOD-1`十的幂总是取模`MOD`，这是素数。 根据费马定理：$$10^k \bmod MOD = 10^{k \bmod (MOD-1)} \bmod MOD$$因为`10`和`MOD`是互质的。 

### 为什么它有效

 以相反的顺序处理规则。 从位置处理完所有规则后`i+1`往后，这一对`(val[d], len[d])`准确描述从数字获得的字符串`d`应用后面的规则后。 

处理规则时`i`，出现在其右侧的每个数字在所有后续替换中都已具有其最终表示形式。 连接这些表示可以精确地产生规则后左侧数字的最终表示`i`以及所有后续规则。 

通过逆向处理顺序的归纳，每个存储的对都保持正确。 合并第一条规则后，每个数字对等于其完整的最终扩展。 原始字符串的最终串联重建了完全变换后的数字的值，模`10^9 + 7`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def solve():
    s = input().strip()
    n = int(input())

    rules = []
    for _ in range(n):
        line = input().strip()
        d = int(line[0])
        t = line[3:]
        rules.append((d, t))

    max_len = 100000
    pow10 = [1] * (max_len + 1)
    for i in range(1, max_len + 1):
        pow10[i] = (pow10[i - 1] * 10) % MOD

    val = [i for i in range(10)]
    length = [1] * 10

    for d, t in reversed(rules):
        cur_val = 0
        cur_len = 0

        for ch in t:
            x = ord(ch) - ord('0')
            cur_val = (cur_val * pow10[length[x]] + val[x]) % MOD
            cur_len = (cur_len + length[x]) % (MOD - 1)

        val[d] = cur_val
        length[d] = cur_len

    ans = 0
    for ch in s:
        x = ord(ch) - ord('0')
        ans = (ans * pow10[length[x]] + val[x]) % MOD

    print(ans)

solve()
```该解决方案为每个数字存储两个数量。`val[d]`是该数字的完全展开模的十进制值`10^9+7`。`length[d]`是扩展长度模数`10^9+6`。 

逆向处理顺序是其核心思想。 当访问一条规则时，出现在其右侧的每个数字都已经知道其最终扩展
