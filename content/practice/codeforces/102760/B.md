 ## 解决方案
 ## 问题理解

 我们有一个甲板包含`A`牌。 他们之中，`B`是炸弹，剩下的牌是安全的。 牌组的顺序是随机的，因此每种可能的炸弹放置位置都有相同的概率。 

玩家开始一个回合`C`健康点并从顶部揭开卡片，直到找到安全的卡片。 每发现一个炸弹都会使生命值减少 5 点。如果在安全卡出现之前生命值达到零或更低，玩家就输了。 任务是计算玩家本回合幸存的概率。 

限制非常小：`A`最多 30 个并且`C`最多 30。这意味着我们不需要高级数据结构或渐近优化技术。 即使是考虑所有可能的炸弹数量的方法也足够了。 然而，浮点精度很重要，因为答案是概率，因此计算应避免不必要的精度损失。 

主要的边缘情况来自生命值和炸弹之间的关系。 粗心的实施可能会错误地计算第一张安全牌，或者在玩家死亡后停止得太晚。 

考虑输入：```
4 2 5
```玩家在一颗炸弹后就输了，因为`5 - 5 = 0`。 唯一幸存的情况是先抽一张安全牌，所以答案是：```
0.500000000
```允许一枚炸弹并随后检查死亡的错误解决方案将产生错误的概率。 

另一种情况是：```
4 2 6
```在这里，玩家在一颗炸弹后幸存下来，因为`6 - 5 = 1`。 只有连续两枚炸弹才会造成损失。 概率为：```
0.833333333
```一个解决方案使用`C // 5`而不是上限值会错误地要求两枚炸弹在此边界上丢失并失败。 

## 方法

 一种直接的方法是模拟第一张安全牌的每个可能的位置。 如果第一张安全卡出现在`k`炸弹，玩家恰好在什么时候生存`k`炸弹不会将生命值降至零。 我们可以计算每个可能值的概率`k`并添加有效案例。 

思考这个问题的一种蛮力方法是枚举这副牌的所有可能排列并计算成功的排列。 由于牌组最多有 30 张牌，这很快就变得不可能了。 可能放置的炸弹数量为`C(30,15)`在最大的情况下，远远超出了可以处理的范围。 

关键的观察是甲板的完整布置是不必要的。 唯一影响结果的是第一张安全牌之前出现了多少炸弹。 我们可以直接计算看到的概率`k`炸弹后面跟着一张安全卡。 

第一个的概率`k`卡片是炸弹是：```
B / A * (B - 1) / (A - 1) * ... * (B - k + 1) / (A - k + 1)
```这些炸弹过后，下一张牌一定是安全的。 那一刻有`A - k`剩下的牌仍然存在`A - B`安全卡，所以下一个因素是：```
(A - B) / (A - k)
```因为玩家只有在到达后才会死亡`ceil(C / 5)`炸弹，我们只需要对较小值的概率进行求和`k`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | ---| ---| ---|
 | 蛮力 | O(2^A) | O(2^A) | O(A) | 太慢了|
 | 最佳 | O(A) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.计算使生命值变为非正值所需的最少炸弹数量。 这个值是`ceil(C / 5)`。 任何炸弹较少的序列都是成功的。 
2. 从概率开始`1.0`对于在第一张安全牌之前抽到零炸弹的情况。 
3. 迭代安全卡之前可能抽取的炸弹数量。 对于每个值`k`，保持第一个的概率`k`卡是炸弹。 
4. 对于当前值`k`，乘以下一张牌安全的概率。 将此概率添加到答案中，因为这代表一种可能的生存结果。 
5. 更新再抽取一枚炸弹的概率并继续，直到所有炸弹都已被考虑或玩家已经失败。 

该算法背后的不变性是在处理值之前`k`，维持的概率恰好代表第一个`k`亮出的牌是炸弹。 乘以下一张牌的概率将该状态转换为第一张安全牌紧随其后出现的机会`k`炸弹。 由于每个可能的生存案例都有唯一数量的先前炸弹，因此将这些概率相加即可得出完整的生存概率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    A, B, C = map(int, input().split())

    need = (C + 4) // 5
    ans = 0.0
    prob_all_bombs = 1.0

    for k in range(need):
        if k >= B:
            break

        prob_safe_next = (A - B) / (A - k)
        ans += prob_all_bombs * prob_safe_next

        prob_all_bombs *= (B - k) / (A - k)

    print("{:.9f}".format(ans))

if __name__ == "__main__":
    solve()
```变量`need`储存导致失败的最少数量的炸弹。 该循环仅考虑较小的值，因为任何较大的数字都无法促成成功的结果。`prob_all_bombs`存储第一个的概率`k`卡片在当前迭代之前是炸弹。 乘以`(B - k) / (A - k)`将此状态推进到下一个可能的炸弹数量。 

表达式`(C + 4) // 5`是整数上限`C / 5`。 当健康状况不是 5 的倍数时，使用正常的整数除法将会失败。 

分母`A - k`表示在抽下一张牌之前剩余的牌数。 自从`A`最多30，浮点精度绰绰有余。

 ## 边缘情况

 对于输入：```
4 2 5
```门槛是一颗炸弹。 该算法从零炸弹的概率开始，然后是安全卡。 这个概率是`2 / 4`，所以答案就变成了`0.5`。 它从不考虑一颗炸弹，因为到达一颗炸弹就意味着死亡。 

对于输入：```
4 2 6
```门槛是两枚炸弹。 该算法首先立即计算安全牌的概率，即`0.5`。 然后它会考虑一枚炸弹，然后是一张安全卡。 这个概率是`(2 / 4) * (2 / 3) = 1 / 3`，给出最终答案`5 / 6`。 

对于输入：```
4 2 20
```玩家需要四枚炸弹才能失去，但牌组中只有两枚炸弹。 该循环涵盖了所有可能数量的炸弹，并将所有可能的结果相加，得出概率`1`。 

对于输入：```
2 1 1
```玩家死于第一颗炸弹。 唯一幸存的安排是先抽安全牌。 该算法会处理此问题，因为循环会在计算致命炸弹案件之前停止。
