 ## 解决方案
 ## 问题理解

 我们有一个无向图。 每个顶点都以唯一的标签开始，标签值是以下数字的排列`1`到`n`。 在该过程的每一轮中，每个顶点都会查看其邻居并保留其中当前存在的最小值。 第一轮使用原始标签，后面的每一轮都使用前一轮产生的值。 

回合结束后`k`，我们计算有多少对不同的顶点具有完全相同的值。 任务是找到所有正轮次中该计数的最大可能值。 

约束条件很大：最多可以有`100000`顶点和`250000`边缘。 重复更新每个顶点的模拟需要了解需要多少轮，甚至一轮已经花费了`O(n + m)`。 由于图可能很大并且答案取决于多轮之后的行为，因此我们需要结构观察而不是直接模拟。 

标签是唯一的，这是一个有用的属性。 当两个顶点在一定轮数后具有相同的值时，它们都从某些可达顶点集中选择相同的最小标记顶点。 重复的最小化操作并不是创建新的值，它只是选择现有的标签。 

有少数情况很容易处理不当。 考虑一个具有单边的图。```
2 1
1 2
1 2
```第一轮之后，两个顶点都收到另一个顶点的标签，因此值为`[2, 1]`答案是`0`。 错误地将原始标签包含为可能的回合的解决方案将计算该对，这是不允许的，因为`k`开始于`1`。 

另一个棘手的情况是明星。```
4 3
1 2 3 4
1 2
1 3
1 4
```一轮结束后，叶子全部收到标签`1`, 给予`C(3, 2) = 3`相等的对。 中心收到最小的叶子标签。 重要的细节是中心和叶子不会永远成为一组，因为图是二部的并且游走的奇偶性很重要。 

最后一种情况是奇数循环。```
3 3
1 2 3
1 2
2 3
3 1
```经过足够多的轮次后，每个顶点都可以通过所需长度的步行到达其他每个顶点。 最终所有顶点都会收到标签`1`，生产`C(3, 2) = 3`。 将每个组件视为二分图会错过这一点，因为奇数循环消除了奇偶校验限制。 

## 方法

 直接的方法是模拟该过程。 对于每一轮，我们扫描每条边并计算两个端点的最小邻居值。 获得新标签后，我们使用频率表计算相等的值。 这是正确的，因为它完全遵循定义。 

问题是决定我们需要模拟多长时间。 图表可以包含长路径，并且语句的轮数没有有用的小界限。 重复`O(n + m)`多轮工作的成本太高。 在最坏的情况下，尝试模拟直到没有任何变化可能会远远超出可能的范围`n = 100000`。 

关键的观察是停止查看值，而是查看哪些原始顶点可以影响之后的顶点`k`回合。 在一轮之后，顶点存储距离为一的顶点中的最小标签。 两轮之后，它存储长度为 2 的游走可到达的顶点中的最小标签。 一般来说，`h^(k)`是通过精确长度的步行可到达的所有顶点中的最小标签`k`。 

对于连接的非二分组件，经过足够的步数后，每个顶点都可以使用所需长度的游走到达每个顶点。 组件中最小的标签会散布到各处，因此整个组件成为一组。 

对于连接的二分组件，每次行走都会交替进行。 经过足够的步数后，一个顶点可以到达由行走长度奇偶性确定的边上的每个顶点。 每侧最小的标签根据圆形奇偶校验扩展到相反侧或同侧。 实际标签不会影响相等对的数量，只有两个颜色类的大小很重要。 

因此，最大值是从每个组件的稳定状态获得的。 组件贡献可以独立添加，因为来自不同连接组件的顶点永远不会相互影响。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 太依赖轮数了，每轮都是`O(n + m)`|`O(n)`| 太慢了|
 | 最佳 |`O(n + m)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 使用 DFS 或 BFS 遍历每个连通分量，同时用两种颜色对图进行着色。 颜色告诉我们该组件是否是二分的，并且还给出了每边的大小。 辅助信息正是控制多轮后可达性的因素。 
2. 遍历组件时，存储是否出现冲突，即一条边连接两个颜色相同的顶点。 这样的冲突证明该组件不是二分的。 对于非二分组件，所有顶点最终都会收到该组件的最小标签。 
3. 对于大小为非二分分量`s`， 添加`s * (s - 1) / 2`到答案。 该组件内的每一对最终都具有相等的值。 
4. 对于具有颜色类别大小的二分组件`a`和`b`， 添加`a * (a - 1) / 2 + b * (b - 1) / 2`。 经过足够多的轮次后，两个颜色类成为两个独立的组，每组内的值相等。 
5. 打印所有组件贡献的总和。 查找组件的过程已经覆盖了整个图，因此不需要模拟哈希轮次。 

为什么它有效：

 之后的顶点值`k`轮数由步行长度可到达的顶点之间的最小原始标签决定`k`。 在连通的非二部图中，足够长的游走可以连接任意两个顶点，因此整个组件的最小标签到达每个顶点。 在连接的二部图中，游走保留边奇偶性，因此只有来自相同颜色类的顶点才能共享相同的最终可达集。 由于每个可达集内选择的标签是唯一的，但对于具有相同可达集的所有顶点来说是相同的，因此最终的组正是二分组件的颜色类和非二分组件的整个组件。 没有早期的回合可以创建更大的组，因为在达到稳定的可达集之前，每一轮都只是对可能的可达顶点的限制。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    labels = list(map(int, input().split()))

    graph = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    color = [-1] * n
    ans = 0

    for start in range(n):
        if color[start] != -1:
            continue

        stack = [start]
        color[start] = 0
        cnt = [1, 0]
        bipartite = True

        while stack:
            v = stack.pop()
            for u in graph[v]:
                if color[u] == -1:
                    color[u] = color[v] ^ 1
                    cnt[color[u]] += 1
                    stack.append(u)
                elif color[u] == color[v]:
                    bipartite = False

        if bipartite:
            ans += cnt[0] * (cnt[0] - 1) // 2
            ans += cnt[1] * (cnt[1] - 1) // 2
        else:
            s = cnt[0] + cnt[1]
            ans += s * (s - 1) // 2

    print(ans)

if __name__ == "__main__":
    solve()
```实现只需要图的遍历。 读取标签是因为它们属于原始定义，但最终相等对的数量仅取决于组件结构，而不取决于标签的实际值。 

这`color`array 执行二分检查。 新组件以颜色开始`0`，并且每条边都要求另一个端点具有相反的颜色。 如果我们发现相同颜色之间的边缘，则该分量包含奇数循环。 

计数`cnt[0]`和`cnt[1]`是二分组件两侧的尺寸。 一组大小内相等对的数量`x`是`x * (x - 1) // 2`，这就是为什么直接使用公式而不是构造最终的哈希值。 

Python 整数不会溢出，但答案可以大到`C(100000, 2)`，因此具有固定宽度整数的语言需要 64 位类型。

 ## 边缘情况

 对于单边图：```
2 1
1 2
1 2
```DFS 找到一个具有颜色大小的二分分量`1`和`1`。 贡献是`0 + 0 = 0`。 这与过程相匹配，因为每个顶点总是接收另一个顶点的标签，因此没有两个顶点共享一个值。 

对于星图：```
4 3
1 2 3 4
1 2
1 3
1 4
```颜色有尺寸`1`和`3`。 该算法添加`C(1,2) + C(3,2) = 3`。 三片叶子具有相同的最终可到达侧，而中心仍位于另一组中。 

对于奇数周期：```
3 3
1 2 3
1 2
2 3
3 1
```DFS 检测到图不能用两种颜色着色，因为相邻顶点在某处需要相同的颜色。 整个组件的尺寸为三，因此它贡献`C(3,2) = 3`。 

对于断开连接的图，每个组件都是单独处理的。 一个组件中的顶点永远看不到来自另一组件的标签，因此添加独立组件贡献会给出正确的全局最大值。
