 ## 解决方案
 ## 问题理解

 我们得到一个由相邻垂直图块组成的直方图。 这`i`-th 瓷砖有宽度`1`和身高`H_i`，因此一组连续的图块形成一个矩形，其宽度是所选图块的数量，其高度受到该组中最短图块的限制。 任务是找到完全适合直方图的最大可能正方形并输出其边长。 正方形的边必须与直方图轴对齐。 

输入包含一个直方图`N`瓷砖及其高度。 输出的不是正方形的面积，而是可以达到的最大边长。 

瓷砖数量可达`300000`，因此检查许多间隔的算法无法工作。 直接搜索所有左右边界对将需要大约`N^2`间隔检查，这远远超出了典型的竞争性编程时间限制所允许的范围。 高度也可以大到`10^9`，因此答案和中间比较必须使用整数运算来处理，而不依赖于小值假设。 

棘手的情况来自于混淆最大的矩形和最大的正方形。 例如，如果直方图是：```
3
100 1 100
```最大的矩形的面积`200`，但最大的正方形有边长`1`，因为唯一宽的区域不够高。 

另一个常见的错误是忘记正方形只能使用大矩形的一部分。 为了：```
5
10 10 10 10 10
```答案是`5`， 不是`10`，因为直方图只有五块宽。 限制因素是宽度和高度中较小的一个。 

最终的边界情况是单个图块：```
1
7
```答案是`1`， 不是`7`，因为一个图块的宽度恰好为 1。 

## 方法

 蛮力的想法是尝试每一个可能的连续范围的图块。 对于每个范围，我们找到其中的最小高度。 该最小高度是该范围的最大可能的正方形高度，而范围长度是最大可能的正方形宽度。 候选答案是这两个值中较小的一个。 

这种方法是正确的，因为每个可能的方块都对应于某些连续范围的图块。 然而，有`N(N+1)/2`范围，大约是`4.5 * 10^10`什么时候`N = 300000`。 即使使用快速的最小查询，检查每个范围也是不可能的。 

关键的观察结果是，某个范围内最短的图块决定了使用该范围的每个方块的最大高度。 我们可以将每个图块视为其周围最佳可能范围的最小高度图块，而不是考虑每个范围。 

对于有高度的瓷砖`h`，我们找到最宽的连续段，其中每个图块的高度至少`h`。 如果该段有宽度`w`，那么该图块作为限制高度的最大正方形的边长`min(h, w)`。 

剩下的挑战是有效地找到这些最广泛的细分市场。 单调递增堆栈恰好给出了该信息。 它允许我们为每个图块找到左侧第一个较小的图块和右侧第一个较小的图块。 这两个位置定义了当前高度可以为最小值的最大范围。 

暴力法之所以有效，是因为每个可能的正方形都属于某个区间。 由于间隔太多而失败。 单调堆栈通过直接查找每个可能的限制高度的最大间隔来消除枚举间隔的需要。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N²) | O(1) | O(1) | 太慢了|
 | 最佳 | O(N) | O(N) | 已接受 |

 ## 算法演练

 1. 从左到右遍历直方图，同时保持平铺索引的单调递增堆栈。 该堆栈存储高度尚未遇到右侧较小瓷砖的瓷砖。 保持高度增加意味着当出现较短的图块时，我们立即知道之前的一些图块已达到其最大宽度。 
2. 当当前高度小于栈顶图块的高度时，将索引一一从栈中移除。 对于每个移除的图块，当前位置是右侧第一个较小的图块，移除后的新栈顶是左侧第一个较小的图块。 
3. 计算移除的图块的最大线段的宽度。 如果左侧没有较小的图块，则该段从直方图的开头开始。 否则，它会在左侧较小的图块之后开始。 宽度是当前索引减去左边界。 
4. 使用移除的图块的高度和计算的宽度来形成正方形候选。 边长不能超过任一尺寸，因此将答案更新为`min(height, width)`。 
5. 在处理完所有较高的图块后，将当前图块索引推入堆栈。 这使堆栈属性对未来的图块保持有效。 
6. 扫描完所有瓷砖后，假装还有一块额外高度的瓷砖`0`。 这会强制删除并处理每个剩余的堆栈元素，覆盖延伸到直方图末尾的范围。 

为什么它有效：

 每个有效的方格都占据一些连续的图块组。 设该组中最短的瓷砖高度为`h`。 组中至少有一个图块的高度准确`h`。 当算法处理该图块时，单调堆栈给出最大可能的间隔，其中每个图块的高度至少`h`。 任何使用高度的正方形`h`不能比这个间隔更宽，并且算法会精确检查它的最佳可能边长。 由于每个可能的方块都有一个相应的最小高度瓦片被考虑，因此算法找到的最大候选者就是真正的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    h = list(map(int, input().split()))

    stack = []
    ans = 0

    for i in range(n + 1):
        cur = h[i] if i < n else 0

        while stack and h[stack[-1]] > cur:
            idx = stack.pop()
            height = h[idx]

            if stack:
                width = i - stack[-1] - 1
            else:
                width = i

            ans = max(ans, min(height, width))

        stack.append(i)

    print(ans)

if __name__ == "__main__":
    solve()
```堆栈存储索引而不是高度，因为需要每个图块的位置来计算其最大有效间隔的宽度。 堆栈的高度不断增加，因此每次较短的图块到达时，移除的图块都会在右侧找到第一个较小的元素。 

与高度的额外迭代`0`是一个哨兵。 它并不代表真正的图块，但它保证所有剩余的高度都被弹出并评估。 如果没有它，则永远不会考虑延伸到直方图末端的图块。 

宽度计算是发生差一错误的主要地方。 如果移除一个图块后堆栈为空，则其左侧没有更小的图块，因此间隔从索引开始`0`并且有宽度`i`。 否则，间隔开始于`stack[-1]`，给出宽度`i - stack[-1] - 1`。

 ## 边缘情况

 对于直方图：```
3
100 1 100
```堆栈首先存储增加的高度`100`，然后遇到`1`。 两人身高`100`瓷砖被弹出，但它们的可用宽度仅为`1`，所以它们产生边长`1`。 高度`1`瓦片可以跨越整个直方图，但它的高度也限制了正方形`1`。 算法返回`1`，匹配真实的最大值。 

为了：```
5
10 10 10 10 10
```所有图块都保留在堆栈中，直到处理哨兵零高度为止。 各高度`10`瓷砖可以覆盖五块瓷砖的整个宽度，但正方形的边长受到宽度的限制。 最佳候选人成为`min(10, 5) = 5`。 

为了：```
1
7
```唯一的方块被哨兵移除。 其宽度计算为`1`，所以候选人是`min(7, 1) = 1`。 这可以防止算法错误地将图块高度视为正方形边。
