 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串`s`长度`n`和另一个二进制字符串`r`长度`n-1`。 该问题描述了一个我们反复缩短的游戏`s`通过用下一个字符替换任何相邻的不同位对`r`。 在每一回合中，我们必须选择一个索引`k`这样`s[k] != s[k+1]`并替换`s[k]s[k+1]`和`r[i]`。 如果不存在这样的对，我们就会立即失败。 目标是确定是否存在允许所有操作的操作序列`n-1`进行替换。 

关键的见解是，如果出现以下情况，游戏就无法开始：`s`不包含相邻的不同位。 如果`s`最初是全部`0`或全部`1`就是，第一步是不可能的。 如果`s`至少有一对不同的相邻对，游戏总是可以继续，直到最后一个角色，因为每次替换都会减少`s`的长度加一，并且选择替换哪对不会限制未来的移动 - 任何移动都会保留至少一个不同的对，除非`s`最后折叠成单个字符。 

这些约束允许所有测试用例最多包含 100,000 个字符，因此我们需要一种能够在线性时间内处理每个字符串的算法。 我们无法模拟所有可能的替换序列，这将是指数级的。 边缘情况包括最初是统一的字符串、具有交替字符的字符串以及长度为 2 的最小长度字符串。例如，`s = "11"`和`r = "0"`必须返回`NO`因为没有移动的可能。 

## 方法

 蛮力方法是模拟每一个可能的动作序列。 对于每个操作，我们都会寻找所有有效的`k`在哪里`s[k] != s[k+1]`，尝试替换，并继续递归。 虽然这可以正确地对游戏进行建模，但它是不可行的，因为序列的数量随着`n`。 在最坏的情况下，我们可能最多`2^(n-1)`要考虑的序列，这对于`n`最多 100,000。 

最佳方法依赖于简单的结构观察：我们立即丢失的唯一方法是字符串不包含相邻的不同位。 一旦存在至少一对不同的对，任何操作都会将长度减少一并留下至少一对不同的对，除非字符串变成单个字符。 因此，游戏可以获胜当且仅当`s`至少包含一个`01`或者`10`子串。 检查此条件可以在字符串上一次完成，使解决方案呈线性`n`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 我们将独立处理每个测试用例。 
2. 对于每个测试用例，请阅读`n`,`s`， 和`r`。 我们不需要`r`因为特定的替换值不会影响移动是否存在。 
3. 迭代`s`从索引 0 到`n-2`。 检查是否有任何连续字符不同。 如果`s[i] != s[i+1]`，立即将此测试用例标记为可获胜。 
4. 如果迭代完成后没有找到不同的对，则将测试用例标记为无法获胜。 
5. 打印`YES`对于可胜诉的案件以及`NO`对于无法胜诉的案件。 

为什么有效：至少存在一对不同的货币对可以保证可以采取行动。 每次移动都会减少长度`s`一个，但总是留下一个有效的对来选择，直到到达最后一个字符。 不变的是，如果存在不同的对，游戏可以继续。 只有字符全部相同的字符串才能通过此检查。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    r = input().strip()
    can_win = any(s[i] != s[i+1] for i in range(n-1))
    print("YES" if can_win else "NO")
```该解决方案使用有效地读取输入`sys.stdin.readline`并直接使用生成器表达式检查条件。 剥离`s`和`r`删除尾随换行符。 使用`any()`确保我们一旦发现不同的对就停止检查。 不存在差一错误，因为我们从 0 迭代到`n-2`比较时`s[i]`和`s[i+1]`。

 ## 边缘情况

 对于长度为 2 的字符串，`s = "11"`和`r = "0"`，算法扫描单个相邻对并发现它相同，输出`NO`正确。 对于一个字符串`s = "01"`长度为 2，算法立即找到不同的对并输出`YES`。 对于较大的字符串，没有`01`或者`10`子串，算法仍然输出`NO`在线性时间内。 这种方法统一处理所有边缘情况，因为它不模拟单独的操作，只检查开始游戏所需的不变量。
