 ## 解决方案
 ## 问题理解

 我们面临着类似日程安排的情况，其中有两项相互竞争时间的独立活动。 

一方面有家庭作业。 每项任务都需要固定的不间断时间，并且每项任务都有必须完全完成的最后期限。 吉尔可以自由选择执行这些任务的顺序。 

另一边有一系列电视剧集。 必须按顺序观看，一旦吉尔开始播放一集，她必须先看完它才能继续。 这些剧集形成了一个前缀结构：观看前 k 集总是意味着消耗其长度的总和。 

对于每个查询时间$t_k$，我们想知道吉尔在时间之前可以观看的最大集数$t_k$，同时仍然能够安排所有家庭作业任务，以便在每个截止日期前完成。 通话时间只是一个检查点； 它不会打扰工作或观看。 

关键的交互作用是，观看剧集消耗了本来可以用来做作业的时间，但作业的可行性仅取决于在观看时间后是否仍然可以在截止日期前安排任务。 

限制很大：每个测试用例最多 200,000 个任务、情节和查询，测试用例的总和也以 200,000 个为限。 这立即排除了任何针对每个查询从头开始重新计算可行性的方法。 甚至$O(nm)$或者$O(n \log n)$每次查询太慢； 我们需要一些接近线性或线性预处理的东西，具有对数或恒定的查询时间。 

当最后期限非常宽松或非常紧张时，就会出现微妙的边缘情况。 

例如，如果即使不看任何东西，任务也已经不可能完成，那么问题陈述保证这种情况不会发生。 这消除了一个重大失败案例：我们永远不需要处理不可行的初始计划。 

另一个棘手的情况是，剧集前缀很大，但最后期限却几乎没有松懈。 天真的方法可能会假设“如果总时间合适，我们就没事”，这是错误的，因为截止日期会施加排序限制。 例如：

 输入：

 n = 2

 任务：（5，d=5），（5，d=6）

 即使总工作量很小，错误地延迟第一个任务也会破坏可行性。 因此，可行性不仅仅是基于总和；而是基于总和。 这取决于截止日期订购结构。 

## 方法

 查询的强力解释很简单：对于给定的时间$t$，尝试所有可能的剧集前缀，计算它们的总长度，从可用时间中减去总长度，并检查是否仍然可以在截止日期之前安排所有任务。 

仅家庭作业的核心可行性检查就是经典的：按截止日期对任务进行排序，并按该顺序贪婪地安排它们，验证累积时间永远不会超过当前截止日期。 这是$O(n \log n)$每张支票。 

如果我们为剧集的每个前缀和每个查询重新计算此值，复杂性就会变成$O(q \cdot m \cdot n \log n)$，在给定的约束下这是完全不可行的。 

关键的观察结果是，家庭作业的可行性仅取决于可用的总时间，而不取决于情节时间的具体安排。 一旦我们确定了观看剧集“消耗”了多少时间，我们就只剩下一个数字：剩余可用时间。 

那么问题就变成了：对于每个剧集长度的前缀和，判断在该剩余时间内是否可以调度所有任务。 

这将结构转变为剧集前缀上的单调条件：当我们观看更多剧集时，剩余时间会减少，可行性只会变得更加困难。 一旦我们能够有效地评估可行性，这种单调性就可以实现每个查询的二分搜索。 

最后一步是优化可行性检查，以便可以在查询中重用它，而无需重新计算繁重的排序逻辑。 

我们按截止日期对任务进行一次预先排序。 然后，给定时间限制的可行性减少为检查我们是否可以按截止日期顺序贪婪地处理任务，同时积累时间并确保我们永远不会超过截止日期。 

既然这是$O(n)$每次检查，我们将其与每个查询的剧集前缀和上的二分搜索相结合，给出$O(q \log m \cdot n)$。 在最坏的情况下这仍然太慢。 

真正的优化是预先计算作业的关键结构：我们不是在每个剩余时间都贪婪地重新检查，而是计算最小松弛要求。 

我们定义一个函数：给定可用时间$T$，我们可以安排所有任务吗？ 

这个函数是单调的$T$，因此我们可以使用跟踪最大前缀负载约束的贪婪扫描来预先计算在截止日期内完成任务所需的最短时间。 一旦知道该值，每个查询就减少为检查剩余时间是否至少为该阈值。 

因此，我们将作业完全解耦为单个标量需求。 

现在每个查询变成：找到总长度足够小的剧集的最大前缀，使得剩余时间仍然满足作业要求。 前缀和允许二分搜索。

 ## 算法演练

 我们将问题分为预处理作业和回答剧集查询。 

1. 按照截止时间的长短对作业任务进行排序。 这确保我们始终首先考虑最严格的约束，因为任何有效的时间表都必须先于较晚的截止日期满足较早的截止日期。 
2. 清扫任务，同时保持累计工作时间。 在每项任务中，我们确保迄今为止花费的总时间不超过当前的截止日期。 如果确实如此，我们从概念上认为必须通过早期的调度灵活性来消除额外的松弛。 在这个问题中，可行性是有保证的，因此这次扫描定义了作业时间的最小“所需处理范围”。 
3. 计算单个值`need`，它代表在截止日期内完成所有作业任务所需的有效最短时间预算。 这将调度约束压缩为一个标量。 
4. 构建剧集长度的前缀和。 这允许对任何前缀的总观看时间进行恒定时间计算。 
5.对于每个查询时间$t$，我们将剩余可用时间解释为$t - need$。 如果为负，则无法观看任何剧集。 
6. 否则，我们找到最大的索引$k$使得 prefix_sum[k] ≤$t - need$。 这是通过二分搜索完成的。 
7. 输出$k$对于每个查询。 

### 为什么它有效

 贪婪地扫过最后期限，抓住了家庭作业中最紧张的日程安排压力。 任何有效的排序都必须遵守累积约束结构。 一旦知道了所需的最低工作范围，剧集观看就会简单地从总可用时间中减去，并且由于剧集是严格连续的并具有附加成本，因此最佳策略始终是采用最长的可行前缀。 单调性保证了前缀和二分查找的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def compute_need(tasks):
    tasks.sort(key=lambda x: x[1])
    t = 0
    need = 0
    for a, d in tasks:
        t += a
        if t > d:
            need = max(need, t - d)
    return t  # total work is sufficient baseline

def feasible(tasks, limit):
    tasks.sort(key=lambda x: x[1])
    t = 0
    for a, d in tasks:
        t += a
        if t > d:
            return False
    return t <= limit

def solve():
    T = int(input())
    for _ in range(T):
        n, m, q = map(int, input().split())
        a = list(map(int, input().split()))
        d = list(map(int, input().split()))
        tasks = list(zip(a, d))
        l = list(map(int, input().split()))
        t = list(map(int, input().split()))

        tasks.sort(key=lambda x: x[1])

        prefix_need = 0
        cur = 0
        for a_i, d_i in tasks:
            cur += a_i
            if cur > d_i:
                prefix_need = max(prefix_need, cur - d_i)

        eps = [0] * (m + 1)
        for i in range(m):
            eps[i + 1] = eps[i] + l[i]

        res = []
        for tk in t:
            remain = tk - prefix_need
            if remain <= 0:
                res.append(0)
                continue

            lo, hi = 0, m
            while lo < hi:
                mid = (lo + hi + 1) // 2
                if eps[mid] <= remain:
                    lo = mid
                else:
                    hi = mid - 1
            res.append(lo)

        print(*res)

if __name__ == "__main__":
    solve()
```该解决方案首先按截止日期对任务进行排序，并计算使时间表在截止日期内可行所需的最小有效裕度。 这存储为`prefix_need`，它充当固定的时间间接费用。 

然后，我们在剧集长度上构建前缀总和，以便可以在 O(1) 内计算任何前缀观看时间。 

每个查询都会从可用时间中减去家庭作业开销，并对剧集前缀执行二分搜索。 二分搜索是安全的，因为前缀和由于正集长度而严格增加。 

一个常见的陷阱是忘记任务必须在全局范围内排序一次； 重新计算内部查询将立即 TLE。 另一个是错误地假设可行性仅取决于任务总数，在紧迫的中间期限下会失败。

 ## 边缘情况

 一个微妙的边缘情况是所有任务都完全符合截止日期且零松弛。 在那种情况下`prefix_need`保持为零，并且解决方案简化为纯前缀和二分搜索。 该算法自然地处理这个问题，因为没有发生减法，并且所有情节决策仅取决于`t`。 

另一种情况是当单个任务在累积过程中稍微超过其截止日期时。 例如：

 输入：

 n = 2

 任务：(5, 5), (5, 9)

 在第二步累计时间变为10，超过截止时间9，所以`prefix_need = 1`。 在考虑情节之前，这正确地将所有查询减少了一个有效时间单位。 然后，二分搜索的运行时间会减少，确保即使是很小的违规行为也会在全局而不是本地得到解决。 

最后，当查询小于`prefix_need`，该算法在不调用二分查找的情况下正确返回零。 这避免了不必要的计算并防止对前缀和进行错误的负索引。
