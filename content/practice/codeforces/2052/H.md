 ## 解决方案
 ## 问题理解

 比赛开始时，汽车按其标签订购：$$1,2,3,\dots,n.$$在比赛中，超车是相邻的交换。 如果有车$x$就在汽车的正后方$y$，那么事件“$x$超越$y$”交换位置。

 比赛结束时我们只知道最终的顺序$c$。 我们必须重建一场包含尽可能多超车的比赛，但有一个限制：对于每一对赛车$(x,y)$，事件“$x$超越$y$“最多可能发生一次，并且该事件”$y$超越$x$“最多可能发生一次。

 我们需要输出最大可能的超车次数以及实现这一目标的一系列超车。 

约束条件$n \le 1000$很小。 汽车的数量最多为$$\frac{1000\cdot999}{2}=499500.$$由于答案本身可以包含$O(n^2)$超越，任何可接受的解决方案在最坏的情况下也至少是二次的。 一个$O(n^2)$施工是完全安全的。 

一个微妙的点是，最大化超车次数与最小化或匹配最终排列不同。 对于最终排名中相对顺序不变的一对赛车，我们可以让它们在比赛中交换两次位置，仍然按原来的顺序完成比赛。 仅执行获得最终排列严格必需的超车的解决方案会错过许多有效的额外超车。 

考虑：```
n = 2
final = [1, 2]
```最终订单已经是初始订单。 一个简单的解决方案将输出零超车。 

最佳比赛是：```
2 overtakes 1
1 overtakes 2
```最后的订单又来了$[1,2]$，但现在我们有两次超车。 

另一个容易被忽略的情况是：```
n = 3
final = [3,2,1]
```每对都是相反的。 没有一对可以贡献两次超越，因为逆转的结局需要相对顺序的净变化。 最多正好有 3 次超车，每对一次。 

## 方法

 蛮力观点从独立考虑每对汽车开始。 

拿一对$(x,y)$和$x<y$。 最初，$x$领先于$y$。 

如果最终排名还$x$领先于$y$，那么两人可以贡献两次超车：```
y overtakes x
x overtakes y
```相对顺序结束不变。 

如果最终排名$y$领先于$x$，那么两人最多可以贡献一次超车：```
y overtakes x
```执行两个方向将恢复原始顺序，这是不允许的。 

这立即给出了一个上限。 让$P$是对的数量，让$I$是最终排列相对于初始顺序的反转计数。 

每个非反转对最多贡献两次超车。 每个反演对最多贡献一个。 

因此$$\text{answer} \le 2(P-I)+I = 2P-I.$$有趣的部分是表明这个界限总是可以实现的。 

关键的观察是，我们可以以非常结构化的方式实现每对车手的第一次超车。 

开始于$$1,2,\dots,n.$$对于每个$y=2,3,\dots,n$， 移动$y$通过相邻的超车一路领先：```
y overtakes y-1
y overtakes y-2
...
y overtakes 1
```处理完所有汽车后，每对$(x,y)$和$x<y$只经历过一次超车，即“$y$超越$x$”。命令变为$$n,n-1,\dots,1.$$现在考虑最终相对顺序实际上应与原始顺序匹配的对。 对于每一对这样的组合，我们都需要在相反方向上进行一次额外的超车。 

从相反的顺序开始，我们将其转换为目标排列$c$使用相邻的交换。 每个相邻的交换完全对应于必须恢复的一对。 这些交换为每个非反转对提供了第二次超越。 

超车总数变为$$P + (P-I)=2P-I,$$它与上限匹配，因此是最优的。

 ## 算法演练

 1. 读取最终排列$c$。 
2. 计算每辆车在最终排名中的位置。 
3. 生成第一阶段。 

对于每一个$y$从$2$到$n$，以及每一个$x$从$y-1$下降到$1$， 输出：```
y x
```这意味着 ”$y$超越$x$”。

 在所有这些超车之后，汽车的顺序变成：$$n,n-1,\dots,1.$$4. 将当前顺序初始化为逆排列。 
5. 将逆排列变换为目标排列$c$。 

从左到右处理位置。 

当车$c[i]$目前处于位置$j>i$，反复向左交换，直到到达位置$i$。 

每个相邻的交换```
[..., y, x, ...]
->
[..., x, y, ...]
```对应超车：```
x y
```记录一下超车情况。 
6. 输出记录的超车总数，然后输出超车本身。 

### 为什么它有效

 对于每对$(x,y)$和$x<y$，第一阶段总是创造一次超车，”$y$超越$x$”。

 在第一阶段之后，每对都处于相反的相对顺序。 

如果最终的排列也需要反转该对，则不需要更多。 这对组合恰好贡献了一次超车。 

如果最终的排列需要原始的相对顺序，那么在从逆排列到$c$，该对必须交换一次。 那个交换正是“$x$超越$y$”。两人贡献了两次超车。

 没有一对选手会在同一个方向上进行两次超车。 第一阶段仅使用“$y$超越$x$”。第二阶段仅使用“$x$超越$y$“对于需要恢复的对。

 Thus every inversion pair contributes one overtake, every non-inversion pair contributes two overtakes, and the total equals the proven upper bound$2P-I$。 结构是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = list(map(int, input().split()))

    events = []

    # Phase 1
    for y in range(2, n + 1):
        for x in range(y - 1, 0, -1):
            events.append((y, x))

    # Phase 2
    arr = list(range(n, 0, -1))
    pos = [0] * (n + 1)

    for i, v in enumerate(arr):
        pos[v] = i

    for i in range(n):
        target = c[i]
        j = pos[target]

        while j > i:
            y = arr[j - 1]
            x = arr[j]

            events.append((x, y))

            arr[j - 1], arr[j] = arr[j], arr[j - 1]
            pos[x] -= 1
            pos[y] += 1

            j -= 1

    out = [str(len(events))]
    out.extend(f"{x} {y}" for x, y in events)
    sys.stdout.write("\n".join(out))

solve()
```第一阶段是完全确定性的。 车$y$恰好超过每辆较小编号的汽车一次。 这会产生相反的排列，并为每对贡献一次超车。 

第二阶段是标准的相邻交换转换。 数组`arr`存储当前订单。 数组`pos`存储每辆车的当前位置，允许每次交换以恒定的时间更新。 

移动的循环`target`left 本质上是目标排列的插入排序风格重建。 每个相邻的交换直接对应于一个有效的超车事件。 

因为 Python 整数是任意精度的，所以不存在溢出问题。 最大可能的事件数量低于一百万，因此存储所有事件完全符合内存限制。

 ## 边缘情况

 考虑：```
2
1 2
```最终排名与初始排名相同。 第一阶段执行：```
2 overtakes 1
```创建相反的顺序。 第二阶段恢复原始顺序：```
1 overtakes 2
```答案是 2，这是最优的，因为两人都贡献了可能的定向超车。 

现在考虑：```
2
2 1
```第一阶段再次执行：```
2 overtakes 1
```并且已经达到目标排列。 第二阶段不执行任何操作。 答案是1。任何增加第二次超车的尝试都会恢复原来的顺序并违反所需的最终排名。 

最后，考虑：```
3
3 2 1
```每对都是倒置的。 第一阶段之后，顺序就已经正确了。 不发生第二阶段交换。 每对都贡献一次超车，这是当最终相对顺序颠倒时可能的最大值。
