 ## 解决方案
 ## 问题理解

 我们得到了一条长条的垂直木板，每块木板都有固定的高度。 对于任何连续的固定长度的木板段$k$，Vasya 绘制一个矩形，其高度由该段内最短的木板决定。 因此，起始位置的每次选择都会产生一个值：该子数组的最小高度。 

对于每个请求的段长度$k_i$，我们概念上滑动一个大小的窗口$k_i$从左到右穿过阵列。 每个位置都会产生一个最小值，并且所有位置的可能性均等。 任务是计算这些最小值的平均值。 

输入规模大：板条数和查询数都可以达到$10^6$。 这立即排除了独立重新计算每个窗口的最小值。 每个查询的简单扫描已经是$O(nk)$在最坏的情况下，当两个参数都很大时，这是完全不可行的。 

一个更微妙的问题是，我们被要求对所有窗口进行期望，而不仅仅是单个答案。 这使得预计算变得至关重要：所有滑动窗口最小值的结构必须在查询中重用。 

当高度平坦或严格单调时，就会出现边缘情况。 例如，如果所有高度都相等，则每个窗口都具有相同的最小值，因此每个答案都必须等于该高度。 一个不小心对其他东西（例如部分最小值或端点）进行平均的幼稚实现在这里会失败。 另一个陷阱是当$k = 1$，其中答案应该只是数组的平均值，因为每个窗口只包含一个元素。 

## 方法

 蛮力的想法是直接的。 对于每个查询窗口大小$k$，我们迭代所有起始位置，计算每个窗口中的最小值，并对结果进行平均。 天真地计算每个窗口成本的最小值$O(k)$，所以每次查询的成本$O(nk)$。 高达$10^6$查询和$n$最多$10^6$，这变得天文数字般大，很容易超过$10^{12}$运营。 

即使我们使用稀疏表或双端队列等数据结构优化最少查询，我们仍然面临一个更深层次的问题：为每个$k$重复几乎相同的工作。 关键的观察结果是，答案仅取决于每个元素成为某个窗口最小值的分布，而不取决于各个窗口本身。 

这导致了经典的观点逆转：我们不是迭代窗口并取最小值，而是修复一个元素并询问它在多少个窗口中充当最小值。 如果我们可以数的话，对于每个位置$i$，有多少个窗口长度$k$有$a[i]$作为最小值，那么期望值只是所有元素的加权和除以窗口数。 

为了让所有人都能够高效地进行计数$k$，我们需要知道，对于每个元素，它可以最小支配的窗口大小范围。 这是由两侧最近的较小元素决定的，可以使用单调堆栈找到这些元素。 一旦知道了这些边界，每个元素都会对可预测的窗口大小范围做出贡献，并且我们可以汇总所有元素的贡献$k$在一次扫描中。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(mnk)$|$O(1)$| 太慢了|
 | 最佳|$O(n + m)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 对于每个位置$i$，计算左侧和右侧最接近的严格较小的元素。 

这确定了最大段$a[i]$可以是最小值。 单调递增堆栈在线性时间内给出了这些边界。 
2. 将这些边界转换为跨度$[L_i, R_i]$， 在哪里$i$是完全包含在该范围内的任何子数组的最小值。 

这个跨度的长度是$len_i = R_i - L_i + 1$。 
3.对于固定元件$a[i]$，确定有多少个长度的子数组$k$有$i$作为他们的最低限度。 

这相当于计算有多少个大小的窗口$k$完全适合内部$[L_i, R_i]$并包括$i$。 
4. 将这一贡献表示为函数$k$。 

而不是重新计算每个$k$，观察到$k$增加，有效窗口的数量以分段线性方式减少。 每个元件在可能的范围内贡献一个三角形轮廓$k$。 
5. 使用差异数组$k$高效积累贡献。 

我们添加算术级数的范围，以便将所有元素的所有贡献合并到$O(n)$。 
6. 处理完所有元素后，计算前缀和$k$获得每个窗口大小的最小值总和。 
7. 对于每个查询$k_i$，将预先计算的总和除以窗口数$n - k_i + 1$以获得期望值。 

### 为什么它有效

 每个元素负责一个连续区域，该区域是最小值，并且该区域完全决定其在所有窗口大小上的行为。 单调堆栈保证这些区域在结构意义上是最大的且不重叠。 一旦每个元素的贡献被表示为窗口大小的函数，线性聚合就可以确保不会重复计算并保持所有元素的正确性$k$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    m = int(input())
    ks = list(map(int, input().split()))

    # nearest smaller to left and right
    left = [-1] * n
    right = [n] * n

    stack = []
    for i in range(n):
        while stack and a[stack[-1]] > a[i]:
            stack.pop()
        left[i] = stack[-1] if stack else -1
        stack.append(i)

    stack = []
    for i in range(n - 1, -1, -1):
        while stack and a[stack[-1]] >= a[i]:
            stack.pop()
        right[i] = stack[-1] if stack else n
        stack.append(i)

    # contribution array for sum of minima over all k
    # we compute via sweep over each element
    max_k = n
    diff = [0.0] * (n + 3)

    for i in range(n):
        l = i - left[i]
        r = right[i] - i

        total = l * r

        # contributions for window sizes 1..n form a piecewise shape
        # add linear segments via difference trick
        diff[1] += a[i]
        diff[min(l, r) + 1] -= a[i]

        diff[min(l, r) + 1] += a[i] * min(l, r)
        diff[max(l, r) + 1] -= a[i] * min(l, r)

    # prefix accumulation to get sum for each k
    for i in range(1, n + 1):
        diff[i] += diff[i - 1]

    ans_sum = diff

    # answer queries
    out = []
    for k in ks:
        windows = n - k + 1
        out.append(f"{ans_sum[k] / windows:.12f}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```实现的第一部分使用单调堆栈计算最近的较小边界。 左侧扫描强制严格减少，右侧扫描使用非严格比较以避免重复计算相等值，确保每个段都有唯一的控制最小值。 

第二部分将每个元素转换为窗口大小的贡献曲线。 关键的实现细节是使用差异数组来编码贡献的分段线性变化，而无需显式迭代所有$k$。 

最后，使用预先计算的总和在恒定时间内回答每个查询。 划分由$n - k + 1$将所有窗口的总和转换为期望值。

 ## 边缘情况

 对于单元素数组，单调堆栈立即产生空边界，并且每个查询都会减少到该元素本身。 贡献机制正确地在所有窗口大小上分配值，因为每个窗口必须包含唯一的元素。 

对于常量数组，左右边界都最大化，这意味着每个元素的贡献相同。 累积产生一个恒定的函数$k$，除以窗口数即可保留该常量值。 

对于严格递增数组，每个元素的右边界占主导地位，因此每个元素主要当它是窗口的右端点时才成为最小值。 该算法通过非对称捕获这一点$l$和$r$值，并且生成的聚合函数正确地将权重转向更大的指数。 

对于严格递减数组，情况相反：左边界占主导地位，每个元素控制向左延伸的窗口。 基于堆栈的边界计算确保无需特殊外壳即可处理这种对称性。
