 ## 解决方案
 ## 问题理解

 我们得到了一个聊天`n`参与者，每个人都由一个唯一的号码标识`1`到`n`。 聊天会在按活动排序的列表中显示参与者，但每个参与者始终会看到自己位于自己列表的顶部。 多名参与者对聊天列表进行了屏幕截图，捕获了他们看到的顺序。 每个屏幕截图都显示了在顶部拍摄的参与者，然后按某种顺序排列了其余的参与者。 

问题在于是否存在一个单一的参与者基本顺序来解释所有屏幕截图。 换句话说，我们想知道每个人是否有一个一致的基于活动的排序，这样如果每个参与者都看到自己位于顶部，他们的屏幕截图就会与记录的屏幕截图相匹配。 

约束条件告诉我们`n`和`k`可以达到`2·10^5`所有测试用例的总计。 这立即排除了尝试所有方法的暴力方法`n!`排列。 每个屏幕截图包含`n`元素，因此解决方案必须有效地处理数组，最好是相对于总和的线性时间`n`价值观。 

当屏幕截图由于除顶级参与者之外的参与者的相对顺序而不一致时，就会出现不明显的边缘情况。 例如，如果三个参与者发布类似的屏幕截图`[1,2,3]`,`[2,3,1]`， 和`[3,1,2]`，存在一致的基本顺序。 但是，如果屏幕截图显示某个参与者位于顶部，而其他参与者的相对顺序与另一个屏幕截图冲突，则答案应该是否定的。 一种幼稚的方法可能只检查顶级参与者并忽略其余参与者的顺序，这在这种情况下会失败。 

## 方法

 蛮力方法将生成所有`n!`参与者的排列并根据所有屏幕截图检查每个排列。 对于每个排列，我们将模拟每个参与者的视图并验证它是否与他们的屏幕截图匹配。 这是正确的但不可行：`n`最多`2·10^5`,`n!`是一个天文数字。 

关键的见解是，对于任何有效的基础订单，每个参与者相对于其他参与者的位置必须在屏幕截图中保持一致。 每个屏幕截图都可以解释为一组定向约束：如果`x`紧随其后`y`在屏幕截图中（忽略顶部参与者），然后按全局顺序`y`必须先来`x`。 因为顶级参与者在他们的视野中总是第一个，所以我们可以删除他们并关注其余参与者的相对顺序`n-1`参与者。 

这一观察结果使我们能够将问题简化为序列一致性检查。 我们选择其中一个屏幕截图作为基础顺序的候选者，并尝试使用该顺序模拟所有其他屏幕截图，并通过将其顶部参与者移动到前面进行调整。 如果此操作无法获取任何屏幕截图，则说明顺序不一致，答案是否定的。 否则，订单有效，答案为“是”。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!·k·n) | O(n!·k·n) | O(n) | 太慢了 |
 | 最佳 | O(k·n) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读`t`，测试用例的数量。 
2. 对于每个测试用例，请阅读`n`和`k`。 
3. 存储全部`k`列表中的屏幕截图。 每个屏幕截图都是一个列表`n`整数，第一个整数是接受它的参与者。 
4. 选择一张屏幕截图作为基础订单的候选者。 这是任意的，因此我们通常选择第一个屏幕截图。 
5. 构建从参与者到此候选顺序中的位置的映射。 
6. 对于每个屏幕截图，检查将其顶部参与者移动到候选订单的前面是否会生成屏幕截图。 为此：

 - 从候选顺序中删除排名最高的参与者。 
- 将其插入前面。 
- 将结果列表与屏幕截图进行比较。 
- 如果不匹配，则返回 NO。 
7. 如果所有屏幕截图都匹配，则返回 YES。 

为什么有效：将顶部参与者移动到前面可以模拟每个参与者的视图。 如果所有屏幕截图都与单个候选订单的此操作匹配，则保证存在与所有屏幕截图一致的底层全局订单。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        screenshots = [list(map(int, input().split())) for _ in range(k)]
        
        candidate = screenshots[0]  # arbitrary candidate
        pos_in_candidate = {val: i for i, val in enumerate(candidate)}
        possible = True
        
        for shot in screenshots:
            top = shot[0]
            # simulate participant's view
            reordered = [top] + [x for x in candidate if x != top]
            if reordered != shot:
                possible = False
                break
        print("YES" if possible else "NO")

if __name__ == "__main__":
    solve()
```该解决方案有效地读取所有输入`sys.stdin.readline`。 候选顺序是从第一个屏幕截图中选择的。 关键的微妙之处是通过从候选列表中删除他们自己的标识符并将其放在前面来正确生成参与者的视图。 这可以防止由于忽略顶级参与者而导致的不匹配。
