 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 在每个场景中都有一排容器，每个容器都装有一定量的水。 我们可以将水移至右侧的容器，但只能从左侧的容器移至右侧的容器。 目标是决定我们最终是否可以重新分配水，以便每个容器最终的水量完全相同。 

唯一允许的操作是定向转移：选择索引 i 和 j，其中 i < j，并将任何非负量的水从 i 移动到 j。 这意味着水只能向右流动，不能向左流动，但可以通过中间位置任意分割和组合。 

所有测试用例中 n 最大为 2⋅10^5 的约束意味着我们每个测试都需要一个线性或近线性的解决方案。 任何二次方的操作，例如模拟转账或重复固定仓位，都会立即失败，因为最坏情况下的总操作量将超过 10^10。 

当除以 n 的总和很小但早期容器太低时，就会出现微妙的边缘情况。 例如，如果第一个元素已经大于目标，我们可能会怀疑失败，但这并不会自动取消资格，因为超出的元素可以被向右推。 相反，如果早期的前缀总和始终低于“应该”的水平，我们可能无法在以后进行补偿，因为水无法向左移动。 

天真的直觉的一个小失败案例是：

 输入：

 n = 3, a = [0, 3, 0]

 目标是1。尽管total 是可整除的，但第一个容器在目标以下开始，但这很好，因为它可以从右侧接收。 然而，如果我们反转方向约束，情况就会发生巨大变化，这暗示方向性是核心难点。 

## 方法

 暴力模拟将尝试重复选择 i < j 组并将水向前推以减少不平衡。 人们可以维持一个循环，扫描目标上方的位置并将多余的位置推到右侧。 在最坏的情况下，每个单位的水可能会移动 O(n) 个位置，并且有 O(sum a_i) 个单位。 这会导致最坏情况下的复杂度约为 10^9 到 10^10 次操作，这是不可行的。 

关键的结构观察是操作约束施加了前缀条件。 由于水只能向右移动，因此前缀中的任何不足都必须在某个早期阶段完全从该前缀内得到满足。 一旦我们通过了前缀边界，我们就永远无法带回水来解决之前的短缺问题。 

这导致了一个干净的不变量：在每个前缀，我们必须有足够的总水来支持使该前缀达到最终的统一水平。 由于最终级别固定为 avg = Total / n，因此前 k 个位置所需的金额恰好为 k * avg。 因此，唯一重要的是运行前缀总和是否低于 k * avg。 

这将问题简化为单个线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n·总计) | O(1) | O(1) | 太慢了 |
 | 前缀余额检查 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算目标值 avg = sum(a) / n。 由于总质量守恒，这是每个容器唯一可能的最终值。 
2. 将运行前缀和变量初始化为 0。 
3. 从左到右迭代数组。 
4. 在每个位置 i，将 a[i] 添加到运行前缀和中。 
5. 计算该前缀所需的数量，即 (i + 1) * avg。 
6. 如果在任何时候前缀和变得严格小于要求，则立即断定这是不可能的。 
7. 如果循环完成且没有违规，则断定这是可能的。

我们与所需前缀总数进行比较的原因是，一旦我们超过索引 i，未来的操作就无法将水带回索引 ≤ i。 因此，可行性完全取决于早期职位是否“欠下”比它们所积累的更多的水。 

### 为什么它有效

 仅向右移动水的过程意味着前缀独立于未来片段朝一个方向演化：未来位置只能帮助其自身及其右侧的位置。 因此，任何前缀赤字都是不可逆转的。 

如果我们想象最终的配置，每个前缀都必须恰好包含其比例的水。 如果在扫描过程中的任何时刻，我们观察到当前的前缀总和小于所需的值，那么即使所有剩余的水都以最佳方式放置，它也无法补偿已经违反的前缀边界，因为该补偿需要将水向左移动穿过边界。 

这个不变量充分表征了可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        total = sum(a)
        avg = total // n
        
        pref = 0
        ok = True
        
        for i, x in enumerate(a):
            pref += x
            if pref < (i + 1) * avg:
                ok = False
                break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```该解决方案首先计算全局目标值。 然后，它在从左到右扫描时维护一个前缀累加器。 关键检查将累积的水量与截至该点所需的均匀分布进行比较。 一旦前缀不足，该函数就会提前停止，因为以后无法进行纠正。 

一个常见的实现陷阱是忘记整数除法在这里是安全的，因为问题保证了整除性。 另一个微妙的问题是使用运行的“差异”而不是显式的前缀比较； 两者都有效，但前缀表述不太容易出错。

 ## 边缘情况

 一个关键的边缘情况是早期元素小于目标但后来的元素包含足够的剩余。 例如，[0, 0, 10]，avg = 3。即使total已经足够，第一个前缀已经违反了要求，因为第一个位置需要3个单位，但有0个单位，并且无法从最终状态解释中的右侧接收。 

另一种情况是数组已经是均匀的。 该算法仍然检查前缀，但从不违反，因此它正确返回 YES，而不执行任何操作。 

最后，单元素数组总是成功，因为不需要重新分配，并且每一步都满足前缀条件。
