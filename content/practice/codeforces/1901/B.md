 ## 解决方案
 ## 问题理解

 我们被要求模拟沿着单元带移动的芯片，其中每个单元最初包含零。 在第一回合中，芯片从第一个单元格开始，在随后的每个回合中，我们可以将其移动到下一个单元格或将其传送到任何单元格。 每次芯片落在一个单元上，该单元中的值就会增加一。 我们的目标是使用尽可能少的传送来到达单元格中的目标整数序列。 

输入由多个测试用例组成。 Each test case has a ribbon length`n`和一个序列`c`长度`n`。 价值`c[i]`指示芯片必须访问单元的次数`i`总共。 由于第一个单元从零开始，但芯片最初放置在那里，因此第一个单元必须具有`c[0] ≥ 1`。 我们需要输出每个测试用例所需的最小传送数量。 

限制条件表明`n`最多可达200​​,000，总和`n`所有测试用例的上限也为 200,000 个。 这排除了任何单独检查每个可能的移动的解决方案。 每个测试用例我们需要一个 O(n) 的解决方案。 

当单元格的目标值小于或等于前一个单元格的目标值时，就会出现微妙的边缘情况。 例如，使用输入`[1,0,1,0,1]`，天真的逻辑可能会假设向前移动总是足够的，但由于某些单元格需要的访问次数比前一个单元格少，因此我们必须向后传送以正确增加它们而不会出现过冲，否则天真的方法将在正确的单元格中产生太少的访问次数。 

另一种边缘情况是具有高目标值的单个单元格，例如`[12]`。 在这里，不需要移动，只需要重复增量，意味着零传送。 它表明该解决方案必须处理不需要移动的序列。 

## 方法

 暴力方法会模拟芯片的每一次转动，明确地计算移动和传送。 从第 1 号牢房开始，如果可能的话移动到下一个牢房，并在必要时传送。 在每一步中，减少该单元所需的剩余访问次数。 这在逻辑上是可行的，但在运算中它是 O(sum of c[i]) 。 由于c[i]可达10^9，因此这种方法是完全不可行的。 

关键的见解来自于观察到向前移动会自动满足严格递增顺序的单元格的最小增量。 换句话说，如果`c[i] > c[i-1]`，我们可以向右移动，让筹码自然增加，因为向前移动算作访问单元格。 仅在以下情况下才需要传送`c[i]`小于`c[i-1]`，因为我们无法“取消访问”单元格。 纠正单元 i 处的缺陷所需的传送次数恰好是`c[i-1] - c[i]`，因为前进的剩余部分必须稍后通过传送回该单元格来重新分配。 

简而言之，我们只总结当目标从一个单元格减少到下一个单元格时的正差异。 通过最初放置芯片，第一个单元格始终算作一次访问。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(c[i] 之和) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 对于每个测试用例，请阅读`n`和目标序列`c`。 
2. 初始化计数器`teleports`到`c[0] - 1`。 这占第一个单元，因为我们最初将芯片放置在那里，所以一次访问是自动的。 
3. 从第二个单元格到最后一个单元格迭代序列。 对于每个单元格`i`， 如果`c[i] < c[i-1]`, 增量`teleports`经过`c[i-1] - c[i]`。 这说明了“纠正”向前移动超调所需的传送数量。 
4.处理完序列后，输出总计`teleports`。 

为什么有效：向前移动会自然地按顺序递增每个单元格。 任何需要比前一个增量更少的单元都不能仅仅依赖于向前移动； 传送是在不超调的情况下满足目标计数的唯一方法。 总结这些缺陷可确保传送的最少数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def min_teleports():
    t = int(input())
    for _ in range(t):
        n = int(input())
        c = list(map(int, input().split()))
        teleports = c[0] - 1
        for i in range(1, n):
            if c[i] < c[i-1]:
                teleports += c[i-1] - c[i]
        print(teleports)

if __name__ == "__main__":
    min_teleports()
```我们首先读取测试用例的数量。 对于每个测试用例，我们读取序列并使用以下命令初始化传送`c[0] - 1`。 迭代数组时，我们只关心某个单元何时需要比前一个单元更少的访问，并将该差异添加到传送计数中。 打印每个测试用例的结果得出解决方案。 使用快速输入可确保我们在最大限制条件下保持在时间限制内。
