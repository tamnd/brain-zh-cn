 ## 解决方案
 ## 问题理解

 我们拥有一组员工，其中每个员工都属于一个公司，并且每个公司的结构都是以首席执行官为基础的层次结构。 如果我们将员工建模为顶点，将上下级关系建模为边，那么每个公司都会形成一棵树，而整个系统就是由这些树组成的森林。 

任务是确定每个公司的规模，这意味着对于每个员工，我们都想知道其相互关联的层次结构中有多少人。 由于同一棵树中的所有员工共享相同的公司规模，因此这相当于计算无向森林中每个连接组件的大小。 

尽管这个故事是用首席执行官和下属来表述的，但计算结构只是一个没有循环的无向图。 每棵树对应一个公司，任何节点的答案就是其树的大小。 

此类问题中的约束通常允许最多大约 200,000 个节点和边，这会立即排除任何二次方法，例如检查每对节点之间的连接性。 任何从每个节点独立尝试重复 DFS 或 BFS 的解决方案在最坏的情况下都会降级为 O(n^2)，这远远超出了可接受的范围。 我们需要对结构进行一次线性或近线性传递。 

当森林包含许多单节点树时，会出现微妙的边缘情况。 例如，如果存在根本没有边的节点，则每个节点都形成一个大小为 1 的公司。另一个极端情况是单个大链，如果不仔细标记，简单的重复遍历可能会多次重新访问长路径。 

## 方法

 暴力破解的想法是将每个节点视为潜在的根，并运行 DFS 或 BFS 来计算可从该节点访问多少个节点。 这是正确的，因为无向图中的可达性准确地定义了连接的组件。 然而，为每个节点独立执行此操作会导致大量重新计算。 在长度为 n 的链中，单个 DFS 的成本已经是 O(n)，重复 n 次会导致 O(n^2) 操作，这是不可行的。 

关键的观察结果是图结构在查询之间不会改变。 每个连接的组件都有固定的大小，并且其中的每个节点共享相同的答案。 这意味着我们只需要计算每个组件一次，然后将其大小传播到该组件中的所有节点。 

有两种标准方法可以有效地实现这一目标。 一种是使用DFS或BFS的图遍历。 我们只访问每个节点一次，在遍历过程中累积其组件的大小，并将该大小分配给每个访问的节点。 第二个是不相交集并集，我们在其中合并边的端点并在 DSU 根中维护组件大小。 

两种方法都依赖于相同的想法：将森林压缩为不相交的集合并计算每个集合而不是每个节点的大小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 来自每个节点的强力 DFS | O(n^2) | O(n^2) | O(n) | 太慢了|
 | 每个组件的 DFS/BFS | O(n) | O(n) | 已接受 |
 | DSU 与尺寸联合 | O(n α(n)) | O(n α(n)) | O(n) | 已接受 |

 ## 算法演练

 我们首先描述 DFS/BFS 方法，因为它是对问题最直接的解释。

1. 从给定的边建立森林的邻接表。 这种表示方式使我们能够有效地遍历每个节点的邻居，而无需扫描不相关的对。 
2. 维护一个所有节点都初始化为 false 的访问数组。 这可确保每个节点只处理一次，从而防止重复遍历同一组件。 
3. 迭代从 1 到 n 的所有节点。 当我们找到一个没有被访问过的节点时，我们就从它开始遍历。 该节点充当新公司树的入口点。 
4. 在遍历过程中，我们执行DFS或BFS，收集从起始节点可到达的所有节点。 每个访问过的节点都会被标记以避免再次访问。 
5. 在遍历组件时，我们计算发现了多少个节点。 这个数字就是当前公司的规模。 
6. 完成组件的遍历后，将计算出的大小分配给该遍历期间收集的每个节点。 

DSU 方法遵循相同的逻辑，但用联合操作代替了遍历。 每条边合并两个集合，每个集合根维护一个大小计数器。 处理完所有边后，每个节点的答案就是其代表的大小。 

工作原理：DFS 中的访问标记或 DSU 中的代表指针可确保每个连接的组件仅被识别一次。 由于连通性将图划分为不相交的集合，因此每个节点都属于一个组件，并且每个组件都只计数一次。 任何节点都不能被计数两次，因为一旦将其分配给组件或在根下联合，就永远不会将其作为单独的实体重新处理。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    g = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)
    
    vis = [False] * (n + 1)
    ans = [0] * (n + 1)
    
    sys.setrecursionlimit(10**7)
    
    def dfs(start):
        stack = [start]
        comp = []
        vis[start] = True
        
        while stack:
            u = stack.pop()
            comp.append(u)
            for v in g[u]:
                if not vis[v]:
                    vis[v] = True
                    stack.append(v)
        
        size = len(comp)
        for node in comp:
            ans[node] = size
    
    for i in range(1, n + 1):
        if not vis[i]:
            dfs(i)
    
    print(*ans[1:])

if __name__ == "__main__":
    solve()
```该解决方案首先构建邻接列表，以便每个员工都知道他们在层次结构中的直接连接。 DFS 使用堆栈迭代实现，以避免递归深度问题，当层次结构退化为长链时尤其重要。 

每次我们遇到一个未访问的节点时，我们都会探索它的整个连接组件。 comp 列表存储该组件中的所有节点，以便在遍历后我们可以为它们分配相同的计算大小。 这可以避免多次重新计算大小。 

ans 数组存储每个节点的最终公司规模，我们打印除索引 0 之外的所有值。

 | 测量| 复杂性 | 说明|

 该算法很容易适应最多 200,000 个节点和边的典型约束，因为它仅执行线性工作。

 ## 边缘情况

 对于单节点图，算法立即将该节点标记为已访问，并为其分配组件大小为 1。 没有要处理的邻居，因此 DFS 堆栈立即清空，并且直接从初始化中得出正确性。 

对于完全断开连接的图，外循环的每次迭代都会触发新的 DFS 调用。 由于不存在边，每个 DFS 只触及一个节点，独立生成正确的大小为 1 的分配。 

对于长链，迭代堆栈确保我们永远不会超出递归限制。 每个节点都被压入和弹出一次，因此即使在最严重的倾斜结构中，遍历也保持线性，没有堆栈溢出风险。
