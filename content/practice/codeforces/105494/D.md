 ## 解决方案
 ## 问题理解

 给定一个整数数组，并要求我们将其分成几组。 解决方案的成本是组的数量，并且每个元素必须恰好属于一个组。 仅当组内部满足两个条件时，该组才被视为有效：元素数量不超过固定限制，并且该组中最小和最大元素之间的差异不超过固定阈值。 

该语句中的关键结构声明是输入中元素的顺序并不重要。 一旦我们对数组进行排序，任何最佳解决方案都可以转换为另一个最佳解决方案，其中每个组对应于该排序数组的一个连续段。 这将问题从任意分区减少到沿线选择切割位置。 

从复杂性的角度来看，数组大小足够大，任何超过 n 的二次方都会太慢。 在最坏的情况下，重复尝试所有分区或重新计算段有效性的解决方案将按 n² 检查的顺序执行，这对于此类典型约束是不可接受的。 

一些边缘情况值得牢记。 如果所有值都相等，则唯一的限制来自大小限制，因此答案只是大小为 k 的块的数量。 如果 k 非常大但值间隔很宽，则由于范围限制，每个元素可能最终会出现在自己的组中。 只检查一个条件而忽略另一个条件的天真贪婪可能会失败。 例如，如果元素的值很接近，但段增长得太长，则忽略大小限制会产生无效的组，即使满足值条件也是如此。 

## 方法

 蛮力视角是考虑每种可能的方式将排序后的数组分割成连续的段，并验证每个分割是否满足这两个约束。 对于每个段，我们将扫描其元素来计算其大小和范围，在最坏的情况下，每个段的时间复杂度为 O(n)。 由于对数组进行分区的方法有多种，这种方法很快就变得不可行。 即使对所有先前的切割位置进行动态编程也会导致 O(n²)，因为对于每个位置，我们都会尝试所有早期的断点并重新计算有效性。 

关键的观察是，一旦数组排序，段的有效性仅取决于其左边界以及我们向右延伸的距离。 当我们扩展一个段时，大小和值范围都会单调变化。 这意味着我们永远不需要重新考虑段内的早期决策：我们可以贪婪地扩展当前段，直到添加下一个元素将违反任一约束，然后我们必须开始一个新段。 

这将问题转化为单个线性扫描，其中每个元素都被处理一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力分区| O(2^n) 或 O(n²) DP | O(n) | 太慢了|
 | 排序数组上的贪婪扫描 | O(n log n)（排序）+ O(n) | O(1) 额外 | 已接受 |

 ## 算法演练

1. 对数组进行非降序排序。 这确保了任何有效的组都可以表示为连续的段，并且段的最小和最大元素始终位于其末尾。 
2. 在第一个元素处开始一个新组。 存储两条信息：当前组的第一个值及其索引位置。 
3. 从左到右迭代数组。 在每个元素处，检查将其添加到当前组是否会违反任一约束。 
4. 如果当前元素与组中第一个元素之间的差异超过允许的阈值，或者组中元素的数量超过 k，则关闭该元素之前的当前组，并在此位置开始一个新的组。 
5. 当开始一个新组时，重置存储的第一个值和位置。 
6. 继续，直到处理完所有元素。 我们开始一个新小组的次数就是答案。 

该实现仅维护当前段的左边界。 这已经足够了，因为数组已排序，因此最小值始终位于左边界，最大值是当前正在考虑的元素。 

### 为什么它有效

 正确性来自于这样一个事实：一旦我们按排序顺序确定了一个组的起点，扩展该组只会使两个约束变得更糟：大小增加一，范围要么保持不变，要么增加。 因此，如果下一个元素违反了约束，则后续扩展无法修复它，并且任何最佳解决方案也必须在该位置进行切割。 与任何最佳排列相比，这确保了尽早进行切割不会增加组的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort()
    
    ans = 0
    first = None
    first_pos = 0
    
    for i, val in enumerate(a):
        if first is None:
            ans += 1
            first = val
            first_pos = i
            continue
        
        if val - first > m or i - first_pos >= k:
            ans += 1
            first = val
            first_pos = i
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先对数组进行排序，这很重要，因为它将分组问题转变为一维分割问题。 变量`first`跟踪当前组中的最小元素，由于排序，该元素始终是最左边的元素。 变量`first_pos`跟踪当前组中到目前为止已包含的元素数量，使我们能够在 O(1) 中强制执行大小约束。 

每次我们检测到添加当前元素会违反范围约束或大小约束时，我们都会立即启动一个新组。 这种贪婪的重启是安全的，因为任何进一步的延长只会恶化这两个约束。

 ## 边缘情况

 当数组包含单个元素时，算法立即开始和结束一组，因为不能违反任何一个约束。 状态会正确重置，因为循环在第一个元素处初始化一个新段，并且之后不会触发剪切。 

当所有元素都相同时，范围条件永远不会触发，因为差异始终为零。 唯一的限制因素变为 k，算法在当前段达到大小 k 时开始一个新组，从而生成大小均匀的块。 

当 k 非常大且 m 非常小时，行为完全由值差距主导。 每当下一个元素超过与当前段起始处允许的差异时，即使段大小仍然远低于 k，算法也会正确分割。 

当m较大且k较小时，每个段都被迫按尺寸切割。 该算法确保了正确性，因为它跟踪段中第一个元素的位置并直接比较索引，而与值无关。
