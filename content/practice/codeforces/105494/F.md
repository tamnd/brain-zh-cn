 ## 解决方案
 ## 问题理解

 我们正在模拟一辆公共汽车穿过一系列交通灯。 在交叉路口之间，公交车会花费固定的行驶时间，并且在每个交叉路口，它可能需要根据周期性交通信号的当前状态进行等待。 

每个交通灯都有自己的周期，由绿色持续时间和红色持续时间定义。 该循环每个固定周期重复一次，并且在零时间，我们被告知光相对于其周期是如何偏移的，从某种意义上说，绿色在行程开始前的一定秒数内处于活动状态。 当公共汽车到达每个十字路口时，我们必须确定当时信号灯是否为绿灯。 如果它是红色的，我们等到它再次变成绿色，然后继续。 

输入描述了一系列交叉点。 对于每个交叉口 i，我们都会得到从前一个交叉口到达该交叉口的行程时间、绿灯持续时间 gi、红灯持续时间 ri 以及描述最后一个绿灯阶段在行程开始前多长时间开始的偏移量 di。 目标是计算公交车完成通过所有交叉路口时的总经过时间。 

约束足够大，不可能模拟每一秒。 即使直接逐步的时间演化也会降低到 O（总时间），在最坏的情况下，如果等待时间累积，O（总时间）可能会非常大。 

当公交车恰好到达绿色和红色之间的过渡点时，就会出现微妙的边缘情况。 如果remi等于gi，那一刻已经是红色的开始，所以需要等待。 另一个边缘情况是当 gi 为零时，这意味着灯始终为红色，并且每次到达都迫使等待一个完整的周期。 

幼稚的实现也可能会错误地处理偏移量 di，特别是当它很大时。 由于 di 可能比循环周期大得多，因此未能以循环为模减少它会导致错误的相位计算。 

## 方法

 暴力模拟将连续跟踪时间，并且对于每个交叉路口，增加时间直到灯变绿。 移动到每个路口后，我们将时间提前ai，然后通过每秒模拟循环来重复检查灯光状态。 这是正确的，因为它准确地反映了真实的过程，但它可能会降低到 O（所有等待的总时间），这在等待时间很长时是不可行的。 

关键的观察是我们永远不需要模拟单个秒。 红绿灯状态是周期性的，因此任何时候我们只需要知道我们在其周期内的位置即可。 我们可以使用模运算直接计算光的相位，而不是一次前进一秒。 

当我们到达交叉路口 i 时，自出发以来经过的时间是已知的。 光的周期每 gi + ri 秒重复一次。 由于最后一个果岭在时间零之前 di 秒开始，因此自该参考果岭开始以来的总经过时间是 time + di。 以循环长度为模减少该值就可以得到循环内的当前位置。 如果这个位置位于绿色区间内，我们立即通过。 否则，我们直接跳到下一个绿色阶段。 

这将每个交集的计算量减少到 O(1)，因为模块化算术取代了模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(总等待时间) | O(1) | O(1) | 太慢了|
 | 模块化仿真| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 让 time 代表从行程开始到现在经过的时间。

1. 将时间初始化为 0。这表示进入第一段之前的时刻，其中未发生任何行程。 
2.对于每个路口i，首先将时间增加ai。 这说明了到达交通灯所需的行驶时间。 
3. 计算自已知绿色参考以来经过的总时间，即totali = time + di。 这改变了我们的时间线，以便我们可以将当前时刻与周期的阶段定义保持一致。 
4. 计算周期 i = gi + ri。 这代表交通信号的完整重复长度。 
5. 计算 remi = Totali mod periodi。 这给出了当前周期内的位置。 模运算之所以有效，是因为信号行为在每个周期都重复相同。 
6. 如果 remi < gi，到达时信号灯为绿色，我们立即出发。 否则，信号为红色，我们必须恰好等待 periodi − remi 秒才能到达下一个绿色相边界。 等待之后，我们将这个延迟添加到时间中。 

处理完所有路口后，时间包含总行驶时间，包括所有等待时间。 

关键的不变量是，在每一步，时间总是反映公交车在完全解决所有先前的等待决策后可以到达下一个路口的最早时刻。 因为每次更新仅取决于当前时间和下一个光周期的确定性模计算，所以未来的决策不取决于我们如何到达当前状态。 该过程在每个交叉点都是局部最优的，因此全局正确。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    time = 0

    for _ in range(n):
        a, g, r, d = map(int, input().split())
        time += a

        period = g + r
        total = time + d
        rem = total % period

        if rem >= g:
            time += period - rem

    print(time)

if __name__ == "__main__":
    solve()
```该解决方案保留单个运行时间变量并在每个交叉点更新它。 行程时间始终先添加，因为到达发生在任何信号检查之前。 

关键的实现细节是操作的顺序：必须在添加偏移量 di 之后计算模数，并且只有当相位为红色时才必须添加等待时间。 使用 rem >= g 可以正确处理灯光恰好在到达时刻切换的边界情况。 

## 工作示例

 考虑一个有两个交叉点的简单情况。 

输入：```
2
3 5 5 0
4 2 3 1
```我们一步步追踪时间。 

对于第一个路口，行驶后时间变为 3。 周期为10。total = 3，rem = 3，小于5，所以我们立即通过。 

对于第二个路口，时间变为 7。total = 7 + 1 = 8，cycle = 5，rem = 3。由于绿色的长度为 2 秒，rem >= 2 意味着我们处于红色，因此我们等待 5 − 3 = 2 秒。

 这确认了只有当模块位置超过绿色窗口时才会触发等待。 

现在考虑一种边缘情况，即公交车恰好到达红色边界。 

输入：```
1
5 3 4 0
```旅行后，时间 = 5。总计 = 5，周期 = 7，rem = 5。由于绿色为 3，所以 rem >= 3 表示红色。 我们等待 7 − 5 = 2，将时间移至 7。 

这表明正好到达果岭边界是不允许通过的。

 ## 边缘情况

 一个重要的边缘情况是到达时间恰好落在红色阶段的开始处。 例如，当 gi = 3、ri = 4 时，如果 rem = 3，则我们正好处于转换位置。 条件 rem >= gi 确保我们将其视为红色并应用等待。 计算出的等待时间是 period − rem，它正确地跳转到下一个绿色开始。 

另一个边缘情况是 di 值较大。 假设di为10^12，而周期较小。 模运算会自动对此进行归一化，因此我们不需要事先显式减少 di 。 例如，如果 period = 6 且 di = 10^12，则 (time + di) % 6 正确捕获相位，而不会溢出或不正确的缩放。 

最后一个微妙的情况是当 gi = 0 时。在这种情况下，rem < gi 永远不会为真，因此每次到达都会触发整个周期的等待。 该公式仍然有效，因为 period − rem 总是前进到下一个循环边界，从而确保正确性而无需特殊的大小写。
