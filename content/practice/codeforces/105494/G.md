 ## 解决方案
 ## 问题理解

 我们得到了一组怪物，每个怪物都由两个数字描述。 一个值代表你需要多少金币才能击败该怪物，另一个值代表你击败它后获得多少金币。 你从一些初始数量的黄金开始，并反复选择要战斗的怪物。 只有当你当前的金币至少达到怪物所需的阈值时，才能与怪物战斗。 击败它后，你的金币会随着它的奖励而增加。 

任务是通过选择最佳的战斗顺序来确定你可以击败的最大怪物数量。 

关键的困难在于顺序很重要。 要求较小的怪物可能会稍后解锁另一个怪物，而奖励较大的怪物可能会更早更有价值，因为它会增加您未来的影响力。 

从约束的角度来看，预期的解决方案必须以大约 O(n log n) 的速度运行。 任何重复扫描所有剩余怪物以选择下一个怪物的方法都会降级为 O(n²)，这对于大输入来说太慢了。 

贪婪直觉的一个微妙的失败案例是，当一个要求稍高的怪物实际上提供了更好的奖励，但无法立即访问时，延迟它会改变其他怪物可用的情况。 例如，如果一个怪物需要 5 个并提供 1 个金币，而另一个怪物需要 4 个并提供 10 个金币，那么首先选择错误的怪物可能会阻止未来的访问，即使在本地看起来更糟。 

## 方法

 直接暴力策略会尝试每种可能的怪物排序并模拟战斗，检查哪些序列有效并最大化计数。 这原则上是正确的，因为它探索了所有排列，但它会阶乘增长，甚至对于中等的 n 也变得不可用。 

一种更结构化的方法是逐步模拟该过程：在每个时刻，考虑您当前可以承受的所有怪物，然后选择一个。 问题是选择哪一个。 关键的观察是，在当前所有负担得起的怪物中，选择奖励最高的怪物始终是最佳选择。 这可以通过本地交换论证来证明：如果您在获得较大奖励时首先选择较小奖励，则交换它们不会使您失去进入未来状态的机会，而只能提高或保留总黄金量。 

这将问题转化为维护一组动态的“可用怪物”并反复提取最佳候选者。 然而，每一步都扫描整个列表仍然太慢。 

为了优化这一点，我们将怪物分为两组：尚未负担得起的和目前负担得起的。 我们维护一个按要求排序的结构，以便我们可以快速将怪物移动到可用的集合中，并维护另一个按奖励排序的结构，以便我们可以快速选择下一个最好的怪物。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 | O(n!) | O(n) | 太慢了|
 | 天真的贪婪扫描每一步| O(n²) | O(n) | 太慢了|
 | 基于堆的贪婪模拟| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们维持两个优先结构。 其中一个存储的怪物仍然无法到达，因为我们缺乏足够的黄金，通过不断增加的需求来订购。 我们目前可以击败的其他商店怪物，按奖励递减排列。 

我们还维护一个代表当前黄金的变量 CW 和一个计数器来表示我们击败了多少怪物。 

流程如下。

1. 将所有怪物插入按所需金币排序的结构中。 这让我们能够快速识别随着CW的增加哪些怪物变得可用。 
2.用初始金币初始化CW，并将所有怪物标记为初始“不可选择”。 
3.将所有要求最多为CW的怪物移至可用池中。 此步骤确保可用池始终准确反映当前时刻可以进行的战斗。 
4. 如果没有可用的怪物，则该过程将停止，因为不可能有进一步的进展。 任何剩余的怪物都需要比所能达到的更多的金币。 
5. 否则，从可用池中选择奖励最高的怪物并击败它。 增加 CW 的奖励并增加答案。 
6. 获得金币后，请重复步骤 3 的过程，因为现在可能会出现新的怪物。 

### 为什么它有效

 在任何时候，在当前负担得起的所有怪物中，可以选择奖励最高的怪物，而不会损失最优性。 如果最佳序列首先选择不同的负担得起的怪物，则将其与最高奖励的怪物交换不会减少后面怪物的可访问性，因为所有要求仅取决于当前的金币，并且交换不会减少未来决策时的金币。 这建立了贪婪选择属性与 CW 的单调增长相结合，确保每一步都是局部最优和全局一致的。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, start = map(int, input().split())
    monsters = [tuple(map(int, input().split())) for _ in range(n)]

    monsters.sort(key=lambda x: x[0])

    i = 0
    cw = start
    ans = 0

    # min-heap by requirement (bi)
    not_ready = []
    # max-heap by reward (gi), store negative
    ready = []

    while True:
        while i < n and monsters[i][0] <= cw:
            heapq.heappush(ready, -monsters[i][1])
            i += 1

        if not ready:
            break

        g = -heapq.heappop(ready)
        cw += g
        ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现依赖于按要求对怪物进行排序，以便我们只扫描它们一次。 指针 i 确保每个怪物只移动到堆中一次，从而使总堆插入成本为 O(n log n)。 

堆将奖励存储为负数，因为 Python 的 heapq 是一个最小堆。 每一步都会从当前可用的怪物中提取最大奖励的怪物，符合贪婪规则。 

当当前不存在可到达的怪物时，就会出现循环终止条件，这意味着 CW 无法进一步增加，因此未来的怪物将不再可用。

 ## 边缘情况

 一种极端情况是最初没有怪物可以承受。 该算法正确地初始化一个空的就绪堆并立即终止，而不会尝试无效的选择，从而产生零。 

另一种情况是多个怪物有相同的要求但奖励却截然不同。 堆确保首先只选择最好的奖励，从而防止弱奖励的次优消耗，从而降低整体覆盖范围。 

最后一种情况涉及一条长链，其中每个怪物都会再解锁一个。 因为每个增益都会立即反映在 cw 中，并且所有新可用的怪物在选择之前都会被推入堆中，所以该算法永远不会错过在过程中可用的新解锁的高奖励选项。
