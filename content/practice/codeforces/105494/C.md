 ## 解决方案
 ## 问题理解

 我们得到了从 1 开始索引的房间序列，我们严格按顺序处理它们。 在浏览房间前缀时，我们维护一个称为当前答案的整数值。 

每个房间都以两种方式之一做出贡献。 进入任何房间总是将当前答案增加一。 此外，一些房间被标记为交叉点，每当我们进入交叉点房间时，当前答案在应用增量后立即加倍。 

任务是按顺序处理所有房间后计算该运行过程的最终值。 

解释这一点的一个有用方法是，答案是通过一系列确定性转换而演变的。 每个步骤都应用固定的“加一”，有时还应用附加的“乘以二”。 困难不在于单个操作，而在于理解重复加倍如何与先前的增量相互作用。 

如果房间最多为 10^5 个，则任何模拟每个房间超过恒定工作量的解决方案都是可以接受的。 然而，试图明确模拟每个早期贡献如何通过未来加倍传播的天真的解释将立即变成二次方，因为每个连接点都可能影响所有先前的贡献。 

当试图“重新计算每个结点的贡献”时，就会出现一种微妙的失败情况。 例如，考虑一个序列，其中每个房间都是一个交汇点。 重复将先前增量的存储总和加倍但同时尝试重新应用历史记录的简单方法将有效地多次重新处理相同的前缀，从而导致每一步线性增长的重复工作。 

另一种边缘情况是根本没有连接点。 那么答案应该是 n，因为我们只对每个房间加一，而从不相乘。 任何假设至少一次加倍或围绕乘法错误初始化的错误实现都会产生错误的结果。 

## 方法

 暴力解释试图直接模拟答案的演变。 我们从零开始，从左到右遍历房间，为每个房间加一，每当遇到交汇点时，我们就把整个当前值乘以二。 

该模拟是正确的，因为它完全遵循所规定的规则。 然而，关键问题隐藏在“现值”代表什么。 当我们乘以二时，我们也隐含地将之前的所有贡献加倍。 如果我们考虑每个单独的 +1 操作的贡献，则每个贡献可能会翻倍多次，具体取决于它后面出现的连接点数量。 

更结构化地计算最终值的直接方法是反转观点。 我们不是跟踪未来的价值，而是跟踪每个位置的贡献被未来的连接放大了多少倍。 每次我们经过一个路口时，它之前的一切都会在其未来影响力中有效地增加二分之一。 这表明连接点的效果是与后缀相乘的。 

关键的观察结果是，每个位置贡献的基值为 1，其最终权重取决于其处或之后出现的连接点数量。 如果后缀中从位置 i 开始有 k 个连接点，则位置 i 的贡献将乘以 2^k。 

这将问题简化为简单的后缀计算：计算右侧剩余的路口数量，并相应地累积贡献。 我们可以按相反的顺序计算后缀计数并一次性更新答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n^2) | O(n^2) | O(1) | O(1) | 太慢了|
 | 后缀加倍计数 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

我们从右到左处理房间，以便我们始终知道后缀中存在多少个交汇点。 

1. 初始化变量`multiplier`到 1。这表示新的 +1 贡献将由于其右侧的结点而缩放多少次。 
2. 初始化`answer`到 0。这将累加最终结果。 
3. 从 n 到 1 遍历房间。 
4. 对于每个房间 i，添加`multiplier`到`answer`。 这反映出当前房间贡献 1，但它受到其后所有连接点的影响，每个连接点的值都会加倍。 
5. 如果房间 i 是一个路口，则乘以`multiplier`到 2。这会更新所有早期房间的效果，因为它们现在将应用更多的未来加倍。 
6.继续直到所有房间都处理完毕，并输出`answer`。 

每个步骤内的操作顺序至关重要。 在更新之前，我们必须首先使用当前乘数应用贡献，因为在考虑基于后缀的加倍时，当前房间不应受到其自身连接状态的影响。 

### 为什么它有效

 关键的不变量是当我们处于位置 i 时，`multiplier`等于 2 严格位于 i 右侧的交汇点数量。 这确保了当我们添加`multiplier`为了得到答案，我们将正确的未来加倍数应用到房间 i 的单位贡献中。 更新中`multiplier`只有在处理完当前房间后才保留这个严格的后缀定义，防止自我影响并保证正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # assuming a[i] = 1 if junction, 0 otherwise
    answer = 0
    multiplier = 1

    for i in range(n - 1, -1, -1):
        answer += multiplier
        if a[i] == 1:
            multiplier *= 2

    print(answer)

if __name__ == "__main__":
    solve()
```该解决方案维护一个正在运行的后缀乘数，用于捕获未来连接点有效加倍单位贡献的次数。 每个房间只贡献一次，并适当缩放，并且连接点会更新所有早期位置的缩放比例。 

一个常见的错误是在添加到答案之前更新乘数，这会错误地将房间自身的连接效应应用到自身。 另一个微妙的问题是假设溢出安全； 在 Python 中，这是自动的，但在固定宽度整数语言中，这需要仔细处理。

 ## 边缘情况

 不是交汇处的单间是最简单的情况。 该算法将乘数设置为 1，相加一次，然后输出 1，这与预期结果匹配，因为从未发生加倍。 

对于单个连接室，该算法在应用任何乘法之前仍然加 1。 由于右侧没有房间，乘数始终保持 1，结果再次为 1。这与加倍仅影响较早房间的事实相符，而且没有房间。 

在完全非结点数组中，乘数永远不会从 1 开始变化。每次迭代恰好加 1，因此最终结果为 n，与仅发生增量的解释相匹配。 

在完全连接数组中，当我们向左移动时，乘数会演变为 1、2、4、8。 每个贡献都通过未来结点的数量进行加权，并且通过反向累加正确地产生最终的几何和。
