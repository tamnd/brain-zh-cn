 ## 解决方案
 ## 问题理解

 我们得到了一系列随时间变化的序列，其中每个元素描述了观察后蚁丘中蚂蚁的数量如何变化。 正值表示蚂蚁添加，负值表示蚂蚁离开。 

我们不知道蚁丘中蚂蚁的最初数量。 相反，我们被告知，在每个时间点，蚂蚁的数量都不能变成负数。 如果我们将初始数字表示为`ans`，然后在处理第一个之后`i`变化时，蚂蚁总数为`ans + p[i]`， 在哪里`p[i]`是第一个的前缀和`i`变化。 限制是该值对于每个前缀都必须保持非负数。 

所以问题归结为选择尽可能小的初始数`ans`这样运行总数在任何时候都不会低于零。 

输入只是更改列表，输出是最小有效起始值。 

从复杂性的角度来看，数组可能足够大，以至于 O(n²) 模拟不可行。 自然的约束是我们只能传递数据一次或固定次数，这指向 O(n) 解决方案。 

显式重建所有前缀和并检查有效性的简单方法仍然是 O(n)，但更危险的简单变体是尝试所有可能的初始值并进行模拟，这将立即爆炸到 O(n·maxValue)。 

当所有变化都是负面的时，就会出现微妙的边缘情况。 例如，如果序列是`[-5, -2, -3]`，前缀和达到`-10`，所以答案必须补偿最深的下降。 另一种边缘情况是当序列在前缀和中永远不会变为负数时，例如`[2, 1, 3]`，其中正确答案为零。 任何忘记考虑前缀最小值的方法都将在这些极端情况之一中失败。 

## 方法

 暴力解释是想象选择初始数量的蚂蚁并模拟该过程。 对于每个候选起始值，我们将遍历数组并维护一个运行总计，检查它是否变为负值。 如果是，则起始值太小，因此我们尝试更大的值。 

这是有效的，因为它在每一步都直接强制执行约束。 然而，对于每个候选者，我们扫描整个数组，在最坏的情况下，我们可能需要尝试与前缀和中的负漂移大小成比例的起始值。 这会导致最坏情况下每个候选的 n 个检查乘积和最多 O(maxPrefix) 个候选，这变得太大了。 

关键的观察是，如果我们假设从零开始，起始值的可行性完全取决于运行前缀和达到的最低点。 如果我们定义前缀和`p[i]`，然后从`ans`将整个曲线向上移动`ans`。 唯一的危险点是最小前缀值，因为这是总和最低的地方。 确保处处非负性等同于确保`ans + min(p) ≥ 0`。 

这将问题分解为计算单个量：最小前缀和。 一旦知道了这一点，最小的有效起始值就是将该最小值提升到零所需的量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n·V) | O(1) | O(1) | 太慢了|
 | 前缀最小跟踪 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从初始化为零的运行总和开始。 如果我们假设起始值为零，则这表示前缀和。 
2. 维护另一个变量，用于存储迄今为止运行总和所达到的最小值。 将其初始化为零，因为在处理任何元素之前，总和为零。 
3. 迭代数组中的每个值，通过添加当前值来更新运行总和。 这模拟增量构建前缀和而不存储它们。 
4. 每次更新后，将当前运行总和与存储的最小值进行比较，如果当前总和较低，则更新最小值。 这抓住了赤字的最深点。 
5. 处理完所有值后，将答案计算为最小前缀和的否定。 这是确保最低点变为零所需的最小向上移动。 

### 为什么它有效

 每个步骤的运行总和表示假设我们从零开始，系统从零漂移了多远。 任何有效的初始值只是将所有这些值向上移动一个常数。 最差的约束始终是最小的前缀和，因为如果该点在移位后为非负，则后面的每个点也为非负。 因此，最佳移位正是使最小前缀和为零所需的量，任何更大的值都不会是最小的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))

    delta = 0
    min_delta = 0

    for v in a:
        delta += v
        if delta < min_delta:
            min_delta = delta

    print(-min_delta)

if __name__ == "__main__":
    solve()
```该解决方案读取序列并仅维护两个变量，当前前缀和和迄今为止看到的最小前缀和。 更新顺序很重要，因为我们想要所有前缀状态（包括初始零状态）的最小值。 

最终的输出是最小前缀和的否定。 如果序列永远不会低于零，`min_delta`保持为零，答案正确为零。 

## 工作示例

 考虑输入序列`[3, -4, 2]`。 

| 步骤| 价值| 前缀和（增量）| 最小前缀 (min_delta) |
 | --- | --- | --- | --- |
 | 开始| - | 0 | 0 |
 | 1 | 3 | 3 | 0 |
 | 2 | -4 | -1 | -1 |
 | 3 | 2 | 1 | -1 |

 最小前缀和为`-1`，所以答案是`1`。 这相当于从一只蚂蚁开始，使最低点恰好达到零。 

现在考虑`[2, 2, 2]`。 

| 步骤| 价值| 前缀和（增量）| 最小前缀 (min_delta) |
 | --- | --- | --- | --- |
 | 开始| - | 0 | 0 |
 | 1 | 2 | 2 | 0 |
 | 2 | 2 | 4 | 0 |
 | 3 | 2 | 6 | 0 |

 前缀永远不会低于零，因此最小值为零，答案也为零。 这证实了不需要赔偿的情况。

 该算法非常适合约束，因为它避免存储前缀数组或执行嵌套计算，使其在输入大小上呈线性。

 ## 边缘情况

 对于包含正数的单元素数组，运行总和永远不会低于零，因此最小前缀为零且输出为零。 对于单个负元素，例如`[-7]`，前缀和立即变为负数，达到`-7`，所以所需的偏移量正是`7`。 该算法可以正确捕获这两种情况，因为它将最小前缀初始化为零，并且仅在出现较低的运行总和时才更新它。
