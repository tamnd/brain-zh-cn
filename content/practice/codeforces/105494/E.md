 ## 解决方案
 ## 问题理解

 我们得到了一系列排列成一条线的山脉高度。 一个参数$k$定义何时两座相邻的山被认为是“兼容的”：如果相邻位置之间的高度差超过$k$，那么该邻接关系就被破坏了。 每当休息发生时，新的山脉就会开始。 换句话说，每个连续段的所有相邻高度差最多为$k$形成一座山脉。 

对于任何固定的$k$，我们可以扫描数组并计算出现了多少个段。 任务是判断是否存在一个值$k$这样产生的山脉的数量恰好是$m$，如果是，则输出最小的这样的$k$。 

输入结构是单个高度序列。 输出是一个整数$k$，或者如果没有这样的情况则声明不可能$k$存在。 

约束条件意味着$n$足够大，可以对所有可能的情况进行二次或重复模拟$k$是不可能的。 即使直接在双循环内检查所有可能的差异也会太慢。 解决方案必须减少对位置数量和高度值范围的依赖。 

当仅对段进行本地推理而不跟踪段数如何变化时，会出现微妙的失败情况$k$成长。 例如，考虑高度$[1, 10, 2]$。 如果$k = 1$，每个邻接都会中断，我们得到三个范围。 如果$k = 9$，一切都连接到一个范围内。 每个索引的范围数量不会平滑变化，只有当$k$跨越特定阈值，即相邻差异。 任何尝试“猜测”的解决方案$k$如果不识别这些阈值，就有可能错过有效的转变点。 

## 方法

 直接的想法是固定一个值$k$并计算出现了多少山脉。 这很简单：我们遍历数组并开始一个新的段$|h[i] - h[i-1]| > k$。 这需要$O(n)$每个查询。 

困难在于$k$可以在很大的间隔内变化，并为每个可能的重新计算分段$k$导致$O(n \cdot H)$行为，其中$H$是可能的高度差的范围。 这是不可能的。 

关键的结构观察是，唯一可以改变的地方是相邻的差异本身。 在两个连续的不同差值之间，分割结构是相同的。 这意味着段数不是所有整数的平滑函数，而是仅在集合中的值处变化的阶跃函数$\{|h[i] - h[i+1]|\}$。 

一旦理解了这一点，我们就可以重新表述问题：而不是改变$k$我们不断地对所有相邻的差异进行排序，并推断其中有多少是“活跃的”（即超过$k$）。 与完全连接的情况相比，每个活动边将段数增加一个。 

如果我们对差异进行排序，我们可以直接确定有多少个大于$k$，它给出了中断的数量，从而给出了范围的数量。 

我们还观察到单调性：增加$k$只能减少或保留段数，不能增加。 这允许二分搜索$k$，但更清晰的解决方案是对差异进行一次排序并直接映射答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解每$k$|$O(nH)$|$O(1)$| 太慢了|
 | 排序差异 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们从考虑范围转变为考虑它们之间的界限。 每个相邻对要么保持连接，要么成为中断，具体取决于其差异是否超过$k$。 

1. 计算所有相邻的绝对差$d[i] = |h[i+1] - h[i]|$。 这些是唯一重要的值，因为它们完全决定了分裂可能发生的位置。 这将问题从连续阈值简化为离散事件。 
2. 对数组进行排序$d$按非递减顺序。 这给出了所有“激活阈值”的全局排序，其中增加$k$导致另一邻接关系建立连接。 
3. 从相反的方向解释该过程：而不是添加连接$k$增加，考虑从所有活动连接开始（大$k$）并逐渐“打破”它们$k$减少。 每次我们传递一个差值时，就会有一个邻接被断开。 
4.观察如果恰好$i$最大差异大于$k$，那么正好$i$存在断点，段数变为$1 + i$。 这将问题转换为计算有多少元素超出$k$。 
5.我们想要的正是$m$段，所以我们需要准确$m-1$休息。 这正是意味着$m-1$值在$d$必须大于$k$。 
6. 按照排序顺序，此条件确定了一个精确的区间：$k$必须位于已排序差异数组中的两个连续值之间。 正确的边界由下式确定$(n-m)$从头开始计数时的第 -th 元素。 
7. 如果区间崩溃或不存在，则无效$k$准确地产生$m$段。 

### 为什么它有效

 分割结构完全取决于哪些相邻边满足$|h[i] - h[i+1]| \le k$。 每条边独立作用，路径图中的组件数量仅取决于删除的边数。 由于边缘去除恰好发生在$k$低于阈值，函数“段数作为函数$k$”仅在排序的差值处发生变化并且是单调的。这确保了从段计数回阈值间隔的映射是明确定义的且唯一的。

 ## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    h = list(map(int, input().split()))

    if n == 1:
        # only one segment always
        print(0 if m == 1 else -1)
        return

    d = [abs(h[i] - h[i - 1]) for i in range(n - 1)]
    d.sort()

    # number of segments = 1 + number of edges > k
    # we want exactly m segments => exactly m-1 edges > k

    if m < 1 or m > n:
        print(-1)
        return

    idx = n - m  # boundary index in sorted differences

    # k must be at least d[idx] to ensure exactly m-1 edges exceed it
    # but also must be strictly less than d[idx+1] if it exists
    lower = d[idx] if idx >= 0 else 0
    upper = d[idx + 1] if idx + 1 < n - 1 else 10**18

    if lower < upper:
        print(lower)
    else:
        print(-1)

if __name__ == "__main__":
    solve()
```代码首先将问题转换为相邻差异，因为只有这些差异才能确定段边界。 对它们进行排序使我们能够全局推理阈值，而不是模拟每个阈值$k$。 

关键指标$n-m$确定必须将多少最大差异视为“断开的连接”才能准确实现$m$段。 答案必须位于由该划分引起的区间内。 如果该区间退化，则没有有效的$k$存在。 

处理边界时需要小心：$m = 1$，我们需要连接所有边，这对应于$k$至少与所有差异一样大。 什么时候$m = n$，每一条边都被打破，对应非常小的$k$。 

## 工作示例

 ### 示例 1

 考虑$h = [1, 5, 2, 8]$,$m = 2$。 

差异是$d = [4, 3, 6]$，排序为$[3, 4, 6]$。 

我们正好需要$m-1 = 1$中断，所以我们希望正好有一个差值大于$k$。 

| 步骤| 已排序 d | 阈值推理| 细分 |
 | --- | --- | --- | --- |
 | 开始 | [3,4,6]| k 非常大 | 1 |
 | 选择 k=4 | [3,4,6]| 只有 6 > k | 2 |

 所以$k = 4$有效，而且是最小的。 

这证实了段计数仅在传递 3、4、6 时发生变化。 

### 示例 2

 考虑$h = [10, 1, 10]$,$m = 3$。 

差异：$[9, 9]$。 

排序：$[9, 9]$。 

要得到 3 个线段，两条边都必须断裂，所以$k < 9$。 

| 步骤| 已排序 d | 状况 | 细分 |
 | --- | --- | --- | --- |
 | k = 10 | k = 10 [9,9]| 没有休息| 1 |
 | k = 8 | [9,9]| 两者都打破了| 3 |

 最小有效值$k$是$8$。 

这表明答案严格低于最小阈值。

 ## 边缘情况

 关键的边缘情况是所有相邻差值都相等。 例如，$h = [1, 10, 1, 10]$。 所有的差异都是$9$。 为了$m = 2$， 任何$k < 9$产生 3 个段，并且任意$k \ge 9$产生 1 段。 没有办法获得正好 2 个段。 排序差异方法可以正确检测到这一点，因为所需的间隔$k$变空。 

另一种情况是当$m = 1$。 为了$h = [5, 2, 8]$，差异是$[3,6]$。 所需的$k$必须至少为 6。算法正确选择上边界，确保单个连接段。 

最后，当$m = n$，每个邻接都必须断开。 对于任何数组，这对应于$k$小于最小差值。 区间构造自然会折叠到“最小元素以下”，并且算法相应地返回最小有效阈值。
