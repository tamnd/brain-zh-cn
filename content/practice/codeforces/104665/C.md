 ## 解决方案
 ## 问题理解

 我们得到了一系列面条，每条面条都带有数字风味值。 我们需要将这些线分成几个盘子。 每道菜必须至少包含$K$菜品的价值被定义为放入其中的菜品中味道最大的菜品。 

任务是将所有串分成有效的菜肴，使菜肴值的总和尽可能大。 

因此，核心决策不仅仅关乎各个股，而是关乎我们如何对它们进行分组，因为只有每个组中的最大元素对分数有贡献，而组中的所有其他元素都是使该组能够存在的有效“支持”元素。 

输入大小可达$10^5$，这会立即排除任何尝试所有分区或重复模拟分组选择的解决方案。 股线数量的任何二次或指数都会失败，因为即使$10^10$在实践中，操作对于 1 秒的限制来说已经太大了。 

一个微妙的点是，每一缕都必须完全属于一道菜。 这将问题变成了划分问题而不是选择问题。 允许丢弃链的天真的解释会完全改变结构并导致不同的、更容易的目标，因此“使用所有元素”约束很重要。 

边缘情况出现时$K = 1$，其中每一股都形成自己的盘子，答案就是所有值的总和。 另一个边缘情况是当$K = N$，其中只能形成一盘，答案是最大元素。 打破贪婪直觉的第三种情况是当大值分散时：如果没有仔细的分组逻辑，人们可能会意外地在组内浪费大值，而这些值不是最大值。 

例如，如果我们有$f = [10, 9, 9, 1, 1]$和$K = 3$，一个粗心的分组，例如$[10, 1, 1]$和$[9, 9]$无效，因为第二组不满足大小要求。 这种错误说明了为什么分组必须遵守全局的最小大小约束，而不是局部的。 

## 方法

 暴力策略将尝试枚举所有可能的方法将数组划分为至少大小的组$K$。 对于每个分区，我们计算所有组的最大值之和。 即使我们将自己限制在有效分区上，分割方式的数量$N$元素增长得非常快，类似于带有附加约束的贝尔数。 为了$N = 20$，这已经远远超出了可行的计算范围，并且在$N = 10^5$，这是完全不可能的。 

关键的观察结果是，在每个组中，只有最大元素很重要，而所有其他元素仅用于满足大小要求。 这造成了强烈的不对称性：大元素只有在成为组最大值时才有价值，而小元素是可互换的填充物。 

一旦我们按降序对数组进行排序，最佳策略在结构上就会变得简单。 我们希望尽可能频繁地将最大的剩余元素分配为组最大值。 每次我们选择最大值时，我们必须“花费”至少$K-1$其他元素形成一个有效的组。 为了最大化总和，我们总是想要那些$K-1$元素尽可能小，为未来的组保留更大的元素。 

这导致了一个贪婪的结构，我们扫描排序后的数组并选择每个$K$-th 元素作为组领导者，因为每个领导者都会消耗自己加上$K-1$填料。

 ## 算法演练

 我们现在描述直接构建最佳分组的建设性策略。 

1. 将所有风味值按降序排序。 

这确保了当我们决定谁成为菜肴的最大值时，我们总是首先考虑较大的候选者，这是必要的，因为较小的元素始终可以用作填充物。 
2. 将累加器的答案初始化为零。 
3. 以步长迭代排序后的数组$K$，从索引 0 开始。 

每个访问的位置对应于选定的菜头。 
4. 将每个访问位置的值添加到答案中。 

原因是该元素成为有效组中的最大值，而下一个元素$K-1$排序顺序中的元素隐式地用作填充符。 
5. 当索引超出数组边界时停止。 

关键的心理模型是我们将排序后的数组分割成连续的大小块$K$，但只有每个块的第一个元素对分数有贡献。 

### 为什么它有效

 排序后，数组按照从大到小的顺序排列。 考虑按此顺序分组。 每当我们选择当前最大的未使用元素作为组最大值时，我们仍然需要$K-1$其他元素。 选择下一个可用的最小元素作为填充者总是最佳的，因为除非它们自己成为领导者，否则它们不会对任何未来的最大值做出贡献，并且延迟大元素成为领导者只能减少其在被迫进入填充位置之前被选择的机会。 

这创建了一个不变量：在每一步中，排序数组的剩余未使用前缀始终包含未来组最大值的最大可用候选者，并且消耗$K$每个组的元素保留了这样的属性：每个选定的领导者都是剩余有效候选人中可能最大的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = [int(input()) for _ in range(n)]
    
    a.sort(reverse=True)
    
    ans = 0
    for i in range(0, n, k):
        ans += a[i]
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案读取所有值，按降序对它们进行排序，然后累加每个值$K$-从索引 0 开始的第一个元素。循环结构直接编码了这样的想法：每组大小$K$只贡献一个有用的值，即排序顺序中的第一个元素。 

一个常见的错误是试图显式地形成组并跟踪剩余的元素。 这是不必要的并且容易出错。 排序步进方法已经隐式编码了最佳分组。

 ## 边缘情况

 当$K = 1$，算法访问排序数组中的每个索引。 例如：```
3 1
5
2
7
```排序后的数组变为$[7, 5, 2]$。 该算法选择索引 0、1、2，生成 14。每个元素形成自己的组，与定义匹配。 

什么时候$K = N$， 例如：```
4 4
1
9
3
2
```排序后的数组是$[9, 3, 2, 1]$。 仅选择索引 0，生成 9。整个数组形成单个有效菜肴，并且最大元素正确代表其风味。 

当值紧密聚集时，例如：```
6 3
8
7
6
5
4
3
```排序后的数组是$[8, 7, 6, 5, 4, 3]$。 该算法选择索引 0 和 3，产生$8 + 5 = 13$。 第一组使用前三个值，第二组使用接下来的三个值，并且在每种情况下最大值是块的第一个元素。
