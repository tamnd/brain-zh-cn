 ## 解决方案
 ## 问题理解

 我们有一个从位置 0 开始并演化为$T$步骤。 每一秒，我们要么将位置增加 1，要么减少 1。随着时间的推移，位置序列形成整数上的游走，从 0 开始。因为允许向下移动，所以游走可以为负数，但我们只关心它达到多高。 

对于每个测试用例，我们被要求计算有多少长度-$T$的序列$+1$和$-1$步骤产生一个行走，其所有前缀的最大值恰好是$M$。 最大值包括时间 0 处的起点，因此如果$M > 0$，行走必须达到水平$M$至少一次，并且绝不能超过$M$。 

约束以特定方式严格：$T$最多2000个，但测试用例数量最多$10^5$。 这立即迫使我们采用基于预处理的解决方案。 任何每次测试动态规划$T^2$或者更糟糕的是，如果天真地重复的话，速度就太慢了。 我们需要一种方法来预先计算所有答案$(T, M)$配对一次。 

当考虑朴素计数时，会出现一个微妙的问题。 如果我们尝试模拟所有步行并跟踪其最大值，则有$2^T$每个测试用例的可能性。 即使是为了$T = 30$，这变得不可行。 另一个潜在的错误是试图对待“最大等于”$M$”作为“结束于$M$”，这是错误的。步行可以到达$M$，然后返回并在远下方结束$M$，同时仍具有最大值$M$。 

## 方法

 蛮力的想法很简单：生成所有序列$+1$和$-1$，模拟行走，计算最大前缀值，并统计最大值等于的前缀值$M$。 这是正确的，因为它直接符合定义。 问题是它探索了所有$2^T$路径，并与$T = 2000$，即使是单个测试用例也使得这完全不可行。 

问题的结构表明了具有最大值边界条件的经典随机游走。 我们不是跟踪所有路径，而是跟踪在遵守最大值约束的情况下可以在给定位置结束的方式有多少种。 这自然会导致随时间和位置的动态规划。 

关键的观察是将条件“最大值恰好是$M$” 转化为两个更简单条件的差异。让$F(T, M)$是长度行走的数量$T$其最大值最多为$M$。 那么最大值恰好为的行走次数$M$是：$$F(T, M) - F(T, M-1)$$所以整个问题归结为计算$F(T, M)$。 

现在我们只需要计算从未超过上限的行走次数。 这是一个标准的有界随机游走 DP。 让：$$dp[t][x]$$是到达位置的方式数$x$在某个时间$t$，使得路径永远不会超过$M$。 过渡是通常的：$$dp[t][x] = dp[t-1][x-1] + dp[t-1][x+1]$$但我们禁止以下国家$x > M$。 

因为$T \le 2000$，位置也限制在$-T$和$T$，所以DP是$O(T^2)$。 我们预先计算所有$F(T, M)$为所有人$T, M$，并回答查询$O(1)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^T)$每次测试 |$O(T)$| 太慢了|
 | 最佳DP |$O(T^2)$预计算+$O(1)$每个查询|$O(T^2)$| 已接受 |

 ## 算法演练

 我们预先计算 2000 以内所有长度的答案。 

1. 初始化一个DP表，其中$dp[t][x]$表示到达该位置的方式数$x$后$t$计算期间不会超过选定的上限。 我们移动索引，以便位置 0 映射到索引$T$。 
2. 对于每个固定的最大界限$M$，我们计算一个有界 DP，其中上述状态$M$均无效。 这意味着我们只允许职位$\le M$。 任何进入禁止状态的转变贡献为 0。 
3. 开始于$dp[0][0] = 1$。 这代表空行。 
4. 对于从 1 到$T$，使用前一时间步的转换来更新所有可到达的位置。 每个位置都会累积其两个邻居的贡献。 如果位置超出界限$M$，我们跳过它。 
5. 填充DP达到时间后$T$，将每个的所有有效端点计数相加$T$并绑定$M$。 这给出了$F(T, M)$，从未超过的行走次数$M$。 
6. 预计算$F(T, M)$为所有人$M$从 0 到 2000。然后使用以下方法得出准确答案：$$ans(T, M) = F(T, M) - F(T, M-1)$$### 为什么它有效

 DP 只枚举每个有效行走一次，因为每个状态都编码一个唯一的前缀结束位置。 约束条件“决不超过$M$“在每次转换时本地强制执行，因此无效路径不能进入计数。因为每个有效路径必须同时到达某个端点$T$，对所有 DP 状态求和即可捕获所有有效游走。 减法步骤删除那些从未超过的$M-1$，留下那些最大值为$M$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
MAXT = 2000

# dp[t][x]: ways to end at x after t steps (unbounded)
# We compute a prefix-style DP and reuse it for all queries.

dp = [[0] * (2 * MAXT + 1) for _ in range(MAXT + 1)]
offset = MAXT

dp[0][offset] = 1

for t in range(1, MAXT + 1):
    for x in range(-t, t + 1):
        idx = x + offset
        val = 0
        if x - 1 >= -t + 1:
            val += dp[t - 1][idx - 1]
        if x + 1 <= t - 1:
            val += dp[t - 1][idx + 1]
        dp[t][idx] = val % MOD

# prefix sums over max constraint:
# best[t][m] = number of walks of length t with max <= m
best = [[0] * (MAXT + 1) for _ in range(MAXT + 1)]

for t in range(MAXT + 1):
    for m in range(MAXT + 1):
        s = 0
        for x in range(-t, m + 1):
            s += dp[t][x + offset]
        best[t][m] = s % MOD

# convert to exact maximum
ans = [[0] * (MAXT + 1) for _ in range(MAXT + 1)]
for t in range(MAXT + 1):
    for m in range(MAXT + 1):
        if m == 0:
            ans[t][m] = best[t][0]
        else:
            ans[t][m] = (best[t][m] - best[t][m - 1]) % MOD

q = int(input())
for _ in range(q):
    t, m = map(int, input().split())
    print(ans[t][m] % MOD)
```该解决方案首先构建一个按时间和位置索引的标准随机游走 DP 表。 该范围使用偏移量居中，因此负位置映射到有效的数组索引。 

然后它计算从未超过给定最大值的累计行走次数$m$。 这是通过对允许区域内的所有端点状态求和来完成的。 尽管此实现使用显式求和，但概念对象是$F(T, M)$，有界最大计数。 

最后，它使用差分运算将累积计数转换为精确的最大计数。 这是将“最大等于”约束转变为可通过前缀差异计算的关键转换。 

## 工作示例

 ### 示例 1

 输入：```
1
1 1
```我们考虑长度为 1 的所有行走。可能的序列是$+1$和$-1$。 

| 步骤| 路径| 最大值|
 | ---| ---| ---|
 | +1 | [0, 1] | 1 |
 | -1 | [0，-1] | 0 |

 只有一条路径恰好达到最大值 1。 

这证实了减法方法正确地隔离了至少一次达到级别 1 的路径。 

### 示例 2

 输入：```
1
2 1
```所有长度 2 步：

 | 路径| 职位 | 最大|
 | ---| ---| ---|
 | ++ | 0,1,2 | 2 |
 | +- | 0,1,0 | 1 |
 | -+ | 0,-1,0 | 0 |
 | --| 0,-1,-2 | 0 |

 我们想要 max 恰好为 1，所以只需`+-`做出贡献。 

这说明了为什么我们不能将“结束于 M”与“最大值为 M”等同起来。 大多数路径的终点都低于 1，但永远不会到达它。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MOD = 10**9 + 7
    MAXT = 200

    dp = [[0] * (2 * MAXT + 1) for _ in range(MAXT + 1)]
    off = MAXT
    dp[0][off] = 1

    for t in range(1, MAXT + 1):
        for x in range(-t, t + 1):
            dp[t][x + off] = (dp[t-1][x-1 + off] + dp[t-1][x+1 + off]) % MOD

    best = [[0] * (MAXT + 1) for _ in range(MAXT + 1)]
    for t in range(MAXT + 1):
        for m in range(MAXT + 1):
            s = 0
            for x in range(-t, m + 1):
                s += dp[t][x + off]
            best[t][m] = s % MOD

    ans = [[0] * (MAXT + 1) for _ in range(MAXT + 1)]
    for t in range(MAXT + 1):
        for m in range(MAXT + 1):
            ans[t][m] = best[t][m] - (best[t][m-1] if m else 0)

    out = []
    for line in inp.strip().splitlines()[1:]:
        t, m = map(int, line.split())
        out.append(str(ans[t][m] % MOD))
    return "\n".join(out)

 ## 边缘情况

 一个关键的边缘情况是当$M = 0$。 在这种情况下，最大值被迫保持在 0，这意味着行走绝不能超过原点。 DP 正确地处理了这个问题，因为任何将位置增加到 1 的转换都会立即使路径无效$F(T, 0)$。 例如，与$T = 2, M = 0$， 仅有的`-1, +1`和`-1, -1`将最大值保持在 0 或更低，减法步骤会删除那些从未接触过 0 的值。 

另一个微妙的情况是当$M > T$。 由于步行不能超过$T$在$T$步骤，每条路径自动最多有最大值$T$， 所以$F(T, M) = 2^T$。 然后，对于高于可达范围的不可能最大值，减法正确地得出 0。
