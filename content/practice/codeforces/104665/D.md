 ## 解决方案
 ## 问题理解

 我们有一个正方形棋盘，尺寸为$N \times N$。 每个单元格都由整数坐标标识，单个骑士棋子从一个单元格开始，而目标单元格固定在棋盘上的其他位置。 马使用标准国际象棋规则移动，这意味着每次移动都会通过八个可能的 L 形偏移之一改变其位置。 

任务是计算从起始单元格移动到目标单元格所需的最少骑士移动次数，或确定根本无法到达目标。 

尽管电路板尺寸可以达到$800 \times 800$，底层结构是一个最多有 640,000 个节点的图，其中每个节点最多有 8 条边。 这立即表明，任何探索棋盘的算法都必须在单元数量上大致呈线性，否则它将无法及时完成。 

多次重新访问状态的直接搜索会太慢，因为可能的路径数量随着深度呈指数增长。 另一方面，具有统一边缘成本的未加权图上的任何最短路径问题自然适合广度优先搜索。 

一个微妙的点是可达性。 马的每一步都会交替方块颜色，因为每一步都会改变奇偶性$x + y$。 如果起始位置和结束位置具有不同的奇偶性，那么答案立即是不可能的。 例如，开始于$(0,0)$并试图达到$(1,0)$在任何板尺寸上给出$-1$，因为马的每次移动都会翻转奇偶性，并且在偶数次移动后，马永远无法保持在相同的奇偶性类别中。 

当开始位置和结束位置相同时会出现另一种边缘情况。 在这种情况下，不需要移动，答案为零。 未明确处理此问题的幼稚 BFS 可能仍然有效，但假设至少一次扩展的错误实现可能会失败。 

## 方法

 一个简单的想法是将每个板单元视为图中的节点并从起始位置执行搜索。 从每个节点，我们尝试所有八个骑士动作并继续，直到到达目标。 这种强力探索本质上是对所有可能的移动序列的搜索。 

这种方法是正确的，因为它最终枚举了所有可到达的位置，但如果没有仔细的结构，它可以通过不同的路径重复地重新访问相同的单元格。 在最坏的情况下，这会退化为探索长度不断增加的指数数量的路径，因为每个位置最多分支为 8 个下一个状态。 

关键的观察结果是所有的行动都有相同的成本。 这将问题转化为在未加权图中寻找最短路径。 在这样的图中，广度优先搜索保证我们第一次到达一个节点时，我们就找到了到达它的最短路径。 这避免了以更高的成本重新访问状态，并确保每个节点最多被处理一次。 

骑士的运动图的结构是固定且稀疏的，因此即使在最大棋盘尺寸下，BFS 也能高效运行。

 ## 算法演练

 ### ## 算法演练

 1. 将问题转化为图遍历，其中每个单元格$(x, y)$是一个节点，每个骑士的移动都定义了到另一个节点的一条边。 这种重新构建是必要的，因为我们不再进行几何推理，而是根据未加权图中的最短路径进行推理。 
2. 检查起始位置和目标位置是否相同。 如果是，答案立即为零，因为不需要移动，否则 BFS 会执行不必​​要的工作。 
3. 使用检查坐标奇偶性$(x + y) \bmod 2$。 如果起始和目标具有不同的奇偶校验，则返回$-1$立即地。 这是因为每次马的移动都会翻转平价，因此无论棋盘大小如何，达到相反的平价都是不可能的。 
4.初始化一个size的距离网格$N \times N$，用标记值填充，例如$-1$，表示未访问的单元格。 该网格跟踪迄今为止发现的到每个单元的最短距离。 
5. 将起始位置推入队列并将其距离设置为零。 队列代表 BFS 边界，总是按距离递增的顺序扩展。 
6. 当队列不为空时，弹出前面的单元格并尝试其中的所有八个骑士动作。 对于每个候选单元格，检查它是否在棋盘内部并且尚未被访问。 如果两个条件都成立，则将其距离指定为当前距离加一并将其推入队列。 这确保通过最短的可能路径发现每个节点。 
7. 如果在扩展过程中到达目标单元格，请尽早停止，因为 BFS 保证我们第一次到达它时是最佳的。 

### 为什么它有效

 BFS 按距离开始增加的层数处理节点。 每次我们从一层移动到下一层时，我们都会将路径长度增加一层。 由于每条边的权重相等，因此在访问节点后不会出现更短的路径。 因此，访问距离网格存储从起点到每个可到达单元格的真实最短距离。 奇偶校验剪枝只是去除不可能的情况，并不影响正确性，因为它是可达性的必要条件。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n = int(input())
    x1, y1 = map(int, input().split())
    x2, y2 = map(int, input().split())

    if (x1, y1) == (x2, y2):
        print(0)
        return

    if (x1 + y1) % 2 != (x2 + y2) % 2:
        print(-1)
        return

    moves = [
        (2, 1), (2, -1), (-2, 1), (-2, -1),
        (1, 2), (1, -2), (-1, 2), (-1, -2)
    ]

    dist = [[-1] * n for _ in range(n)]
    q = deque()
    q.append((x1, y1))
    dist[x1][y1] = 0

    while q:
        x, y = q.popleft()
        if (x, y) == (x2, y2):
            print(dist[x][y])
            return

        for dx, dy in moves:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < n and dist[nx][ny] == -1:
                dist[nx][ny] = dist[x][y] + 1
                q.append((nx, ny))

    print(-1)

if __name__ == "__main__":
    solve()
```该解决方案使用双端队列维护 BFS 队列，以便插入和删除都可以$O(1)$。 距离数组确保每个单元仅被处理一次，从而防止通过不同路径重复探索同一位置。 边界检查保证我们永远不会离开董事会。 

尽早进行奇偶校验以避免在已知答案不可能时进行不必要的内存分配和遍历。

 ## 边缘情况

 当开始等于目标时，BFS 循环通常仍会初始化队列并开始扩展，但正确的行为是立即返回零。 该算法在任何处理之前都会明确检查这一点，因此不会发生不必要的遍历。 

当起始和目标的奇偶性不同时，BFS 将探索整个连接的组件，而不会到达目标。 在大型板上，这会浪费时间，但奇偶校验会立即检测到不可能。 例如，输入：```
8
0 0
1 0
```回报$-1$立即因为$(0+0)\%2 \neq (1+0)\%2$。 

在最小的板上，例如$1 \times 1$，唯一有效的位置是$(0,0)$。 任何其他目标都是无效的，并且 BFS 永远不会将任何有效的移动放入队列。 该算法自然地处理这个问题，因为所有生成的移动都落在网格之外并被边界检查丢弃，使队列为空并产生$-1$除非开始等于目标。
