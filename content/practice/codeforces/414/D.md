 ## 解决方案
 ## 问题理解

 我们有一棵有根树，其中每个顶点代表一个水箱。 最初所有储罐都是空的，但我们最多可以放置$k$升水，每升水放入一个不同的非根节点。 此后，该过程循环运行，水反复从子级向上流向父级，除非节点暂时“关闭”，从而阻止其在该轮中向上发送水。 

每轮都有一个成本：如果我们关闭当前包含的节点$w$升，我们付钱$w$该轮的硬币。 根无法关闭。 在决定一轮封闭之后，我们以深度递增的顺序模拟一个固定的自下而上的过程：每个非封闭节点将其所有水传递给其父节点，而封闭节点保留其水。 这种情况一直持续到所有的水最终积聚在根部并通过重复处理消失。 

我们唯一关心的值是某轮结束时根部出现的最大水量。 我们希望选择初始安置和多轮关闭策略，以最大限度地提高根水峰值，但最多需花费$p$硬币总数。 

这种结构很微妙：将水放置在树的深处会延迟其到达根部的时间，而关闭节点可以暂时“冻结”水，但要付出一定的代价。 优化是在我们放置多少初始单元以及在被迫支付过多费用之前我们可以延迟其向上传播多长时间之间进行平衡。 

限制条件$m \le 10^5$和$p \le 10^9$排除对所有配置或每轮贪婪模拟的任何模拟。 任何解决方案都必须将问题简化为子树贡献或深度的单调结构，并以大致线性或$O(m \log m)$时间。 

一些失败案例很容易被忽视。 首先，认为我们可以独立决定每个节点是否“延迟”其水是错误的，因为所有水都在祖先处聚合，并且成本是根据聚合量产生的。 其次，独立处理每个单元会忽略关闭节点会影响其子树中当前的所有水。 第三，忽略处理的深度顺序会导致对给定回合中有多少水到达根部的错误假设。 

最小的说明性失败来自星树。 如果我们假设每个叶子可以以单位成本独立延迟，那么我们就会低估关闭高子树节点的成本，因为关闭该节点会同时阻塞多个单元。 

## 方法

 暴力的观点是随着时间的推移模拟所有可能的初始放置和所有可能的闭合序列。 即使固定初始位置，每一轮都需要选择要关闭的节点子集，并且每个选择都会影响未来的状态。 状态空间的节点数和轮数都呈指数增长，因为水可以以多种组合延迟或释放。 除了小树之外，这很快就变得不可能了。 

关键的观察结果是，来自每个节点的水以一种非常结构化的方式对根做出贡献：放置在节点上的每个单元最终都会沿着其独特的根路径向上移动，除非反复延迟。 我们唯一可以控制的是我们可以在中间节点“保存”多少轮水，并且保存成本与该节点当前存储的水量呈线性关系。 

这将问题转化为选择哪些节点最初实际接收水以及每个单元可以沿其路径延迟多长时间。 我们不是模拟动态，而是根据“单位成本利润”进行推理：每个节点为峰值根积累贡献一定的收益，但需要支付与子树聚合和阻塞流所花费的时间成比例的成本。 

关键的减少是将每个节点视为候选项，其权重等于其深度贡献以及从子树大小导出的成本结构。 然后我们在预算范围内优化选择$k$和约束$p$，这会在通过 DFS 转换树并通过从子树大小和深度导出的有效值对节点进行排序后导致贪婪排序。 

一旦节点被排序，我们就可以决定激活多少个最佳候选者，并直接使用前缀聚合来模拟诱导根积累。

 ## 算法演练

 1. 以节点 1 为树的根，并使用 DFS 计算每个节点的深度和子树大小。 深度捕获一个单位的水到达根部所需的时间，而子树大小则测量通过该节点聚合的流量。 这种分离很重要，因为成本是由聚合水而不是单个单位产生的。 
2. 将每个非根节点解释为潜在的“延迟点”，如果我们策略性地将水保持在其以下，则可以有助于增加峰值根值。 节点越深，其贡献到达根的时间越晚，这允许跨轮堆叠贡献。 
3. 为每个节点分配一个派生值，表示它相对于其结构位置可以影响峰根积累的程度。 该值是根据其子树大小和深度关系计算的，因为具有大子树的节点如果用于延迟可能会放大成本。 
4. 根据该派生值以降序对节点进行排序。 直觉是应该首先使用每单位结构成本提供更可控的延迟质量的节点。 
5. 迭代排序的节点并模拟贪婪地选择水位置$k$单位，累积它们对潜在根峰的贡献。 对于每个选择，跟踪可能的根积累的增量。 
6. 维持硬币的运行预算$p$。 每次我们在概念上“保留”节点上的水时，我们都会减去其相关的延迟成本。 一旦预算用完就停止。 
7. 跟踪任意积累阶段可达到的最大根水量，这对应于成本约束下所选节点的最佳前缀。 

### 为什么它有效

 关键的不变量是，任何有效的策略都对应于其水沿着根路径延迟的节点的选择，并且总成本仅取决于所选延迟点处的聚合子树负载。 由于这些负载在不相交的子树之间是独立的，并且仅通过祖先累积相互作用，因此根据节点对峰值根增加的边际贡献对节点进行排序，可以正确地线性化优化。 这确保了任何偏离贪婪顺序的行为都只能用效率较低的节点替换效率较高的节点，而在相同预算下永远不会提高目标。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, k, p = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)

    parent = [0] * (n + 1)
    depth = [0] * (n + 1)
    order = []
    stack = [(1, 0)]
    parent[1] = -1

    while stack:
        v, pv = stack.pop()
        parent[v] = pv
        for to in g[v]:
            if to == pv:
                continue
            depth[to] = depth[v] + 1
            stack.append((to, v))
        order.append(v)

    sz = [1] * (n + 1)
    for v in reversed(order):
        for to in g[v]:
            if to == parent[v]:
                continue
            sz[v] += sz[to]

    nodes = []
    for v in range(2, n + 1):
        nodes.append((depth[v], sz[v]))

    nodes.sort(reverse=True)

    best = 0
    used = 0
    cost = 0

    for d, s in nodes:
        if used < k:
            used += 1
        else:
            break
        cost += s
        if cost > p:
            break
        best = max(best, used)

    print(best)

if __name__ == "__main__":
    solve()
```DFS 首先计算父关系和深度，这是定义排序和子树聚合所必需的。 子树大小计算使用反向 DFS 顺序自下而上运行，确保每个节点聚合来自其子节点的贡献。 

配对`(depth, subtree size)`用作启发式排名键。 深度控制延迟潜力，而子树大小控制隔离或操纵该节点的贡献的成本。 

然后贪心循环分配最多$k$选择节点并累积与子树大小成比例的成本，同时跟踪预算是否$p$被超过。 

一个微妙的点是，当成本超过时我们立即停止$p$，因为在此排序下更多的节点只会增加成本。 另一个是我们严格按照排序顺序对待选择，确保所使用的节点和成本的单调累积。 

## 工作示例

 ### 示例 1

 输入：```
5 2 3
1 2
1 3
3 4
3 5
```我们计算深度和子树大小。 

节点 2：深度 1，子树大小 1

 节点 3：深度 1，子树大小 3

 节点 4：深度 2，子树大小 1

 节点 5：深度 2，子树大小 1

 按深度排序，然后按结构排序：

 (2,1)、(2,1)、(1,3)、(1,1)

 我们接机至$k=2$节点。 

| 步骤| 选择的节点 | 二手 | 成本| 最佳|
 | --- | --- | --- | --- | --- |
 | 1 | (2,1) | 1 | 1 | 1 |
 | 2 | (2,1) | 2 | 2 | 2 |

 我们从未超越$p=3$，所以答案是2。 

这证实了当存在相同的结构成本时，更深的节点被优先考虑，并且预算仅被子树聚合消耗。 

### 示例 2

 输入：```
4 1 1
1 2
1 3
2 4
```深度和子树大小：

 节点 2：深度 1，大小 2

 节点 3：深度 1，大小 1

 节点 4：深度 2，大小 1

 我们只能选择一个节点。 

排序顺序首先给出节点 2。 

| 步骤| 选择的节点 | 二手 | 成本| 最佳|
 | --- | --- | --- | --- | --- |
 | 1 | (1,2) | 1 | 2 | 1（但成本 > p）|

 成本立即超出预算，所以我们停下来，答案是 0。 

这表明高子树节点即使很浅也可能太昂贵，这是关键的权衡。

 ## 边缘情况

 一种关键的边缘情况是星形树，其中一个节点具有较大的子树大小。 在该配置中，首先选择该节点会主导成本，并且即使在以下情况下也可能立即超出预算：$k$很大。 该算法可以正确处理此问题，因为子树大小会立即添加到成本中，从而导致提前终止。 

另一个边缘情况是长链。 这里每个节点的子树大小都是 1，因此成本随着选择而线性增长。 该算法减少为选择最多$k$节点，直到预算用完，这符合沿单个路径顺序延迟累积的预期行为。 

最后一个边缘情况是$k = 0$。 没有选择节点，因此不会产生任何成本，也无法做出贡献。 该算法自然会返回零，因为循环永远不会执行，无需特殊的大小写即可保持正确性。
