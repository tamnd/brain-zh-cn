 ## 解决方案
 ## 问题理解

 我们被赋予了多个独立的场景。 每个场景提供三个正整数，表示骨折后留下的三个骨头碎片的长度。 对于每个三元组，我们必须决定这三个长度是否可以作为非退化三角形的边长。 

有效的三角形要求任意两条边的总和严格大于第三条边。 对于给定长度的所有三个成对组合，此条件必须成立。 

输出只是每个测试用例的是或否决定，具体取决于三角不等式是否成立。 

这些约束允许每个长度最大为 10^8，这立即排除了对标准整数算术之外的特殊数字处理的任何需要。 测试用例的数量没有明确限制，但典型的 Codeforces 格式意味着潜在的大输入流，因此每个用例必须在恒定时间内处理。 

尝试构建或模拟几何体的简单方法是不必要的。 唯一有意义的操作是比较数字对的总和。 

边缘情况主要与平等和顺序有关。 一个常见的错误是忘记三角形必须是非退化的，因此等式是无效的。 例如，像 1 2 3 这样的输入会失败，因为 1 + 2 等于 3，这不能形成有效的三角形。 另一个微妙的情况是当所有边都相等时，例如 5 5 5，它始终有效，因为 5 + 5 严格大于 5。 

## 方法

 思考这个问题的一种强力方法是直接应用三角形的定义：检查每个测试用例的所有三个不等式。 由于只有三个数字，这已经是每个案例的持续工作，因此除了进行冗余或重复计算之外，没有任何有意义的“慢”版本。 

人们可以想象一种误导的方法，即我们尝试排列边或模拟三角形构造，但这将是不必要的开销。 问题的结构纯粹是相关的：只有比较才重要。 

关键的简化来自于认识到三个不等式中，只有一个不等式在排序后需要仔细检查。 如果我们对边重新排序，使得 a ≤ b ≤ c，那么唯一潜在的重要条件是 a + b > c 是否存在。 其他两个不等式自动成立，因为 c 是最大值。 

这将问题减少到每个测试用例进行一次比较。

 | ---| ---| ---| ---|
 | 直接不平等检查 | 每个案例 O(1) | O(1) | O(1) | 已接受 |
 | 排序+单项检查 | 每个案例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 ### 最佳方法

 1. 读取整数的三元组，直到输入结束。 每个三元组代表三个候选边长。 
2. 对于每个三元组，对值重新排序，使它们处于非递减顺序。 此步骤隔离最大值，这是唯一可能违反三角形条件的值。 
3. 将两个较小值的总和与最大值进行比较。 如果总和严格更大，则这三个线段可以形成一个三角形。 
4. 如果条件成立则输出“si”，否则输出“no”。 

排序步骤不在于效率，而在于减少需要检查的条件数量。 如果没有排序，我们需要显式检查所有三个不等式，但排序保证其中两个不等式是多余的。 

### 为什么它有效

三角形不等式要求所有两两之和超过余下边。 一旦对值进行排序使得 a ≤ b ≤ c，不等式 a + c > b 和 b + c > a 就自动成立，因为 c 是最大的，并且 b 和 c 都是正数。 唯一可能失败的约束是两个最小值加起来是否足够大以超过最大的值。 如果失败，则相同值的任何排列都不能满足三角形条件，因为任何其他配对只会减少与 c 相比的总和。 

这种减少依赖于有序值的单调结构：最大的元素主导所有涉及它的比较。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    out = []
    for line in sys.stdin:
        if not line.strip():
            continue
        a, b, c = map(int, line.split())
        if a > b:
            a, b = b, a
        if b > c:
            b, c = c, b
        if a > b:
            a, b = b, a

        if a + b > c:
            out.append("si")
        else:
            out.append("no")
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现逐行处理输入，对于给定的问题格式来说这已经足够了。 每个三元组都使用最小交换序列而不是完整排序来排序，因为只涉及三个元素。 

核心决策是单一不等式`a + b > c`。 严格的不平等是必不可少的，因为平等对应于退化三角形，这是明确不允许的。 

输出累积在列表中并打印一次，以避免重复的 I/O 开销。 

## 工作示例

 ### 示例 1

 输入：```
3 4 5
```排序后，值仍保留 (3, 4, 5)。 

| 步骤| 一个 | 乙| c | 检查 |
 | ---| ---| ---| ---| ---|
 | 输入 | 3 | 4 | 5 | 原料|
 | 已订购 | 3 | 4 | 5 | a ≤ b ≤ c |
 | 比较 | 3 | 4 | 5 | 3 + 4 > 5 | 3 + 4 > 5

 结果为真，因此输出为“si”。 

这展示了一个标准的有效三角形，其中所有不等式都严格满足。 

### 示例 2

 输入：```
9 2 4
```排序后，值变为(2,4,9)。 

| 步骤| 一个 | 乙| c | 检查 |
 | ---| ---| ---| ---| ---|
 | 输入 | 9 | 2 | 4 | 原料|
 | 已订购 | 2 | 4 | 9 | a ≤ b ≤ c |
 | 比较 | 2 | 4 | 9 | 2 + 4 > 9 | 2 + 4 > 9 |

 由于 6 不大于 9，因此三角形条件失败。 

这个案例凸显了为什么排序很重要：最大的一边主导着可行性检查。

 ## 边缘情况

 一个微妙的边缘情况是三角形几乎退化的时候。 例如，`1 2 3`排序后变成`(1, 2, 3)`。 该算法计算`1 + 2 = 3`，并且由于需要严格的不平等，因此它正确地输出“no”。 使用的弱实现`>=`而不是`>`会错误地接受这个案例。 

另一种情况是当输入已经按相反顺序排序时，例如`9 2 4`。 基于交换的排序确保了正确的标准化`(2, 4, 9)`，之后应用相同的单一比较。 如果没有排序，简单的检查可能会错误地比较不匹配的对，但仍然会得到正确的结果，但在这个问题的更复杂的扩展中，该方法会失败，从而使排序步骤成为稳定的一般模式。
