 ## 解决方案
 ## 问题理解

 我们得到了服务窗口的线性序列，并且在每个窗口处，文档之间恰好存在一种可能的转换：如果您当前持有特定文档，则可以选择执行将其转换为另一个文档的过程。 执行过程不会删除原始文档，因此您的文档集合只会随着时间的推移而增长。 

你从文档 0 开始，你的目标是最终获得文档 m−1。 关键的限制是窗口是严格排序的：一旦你移过一个窗口，你就永远不能回来，因此每个窗口提供的转换最多只能使用一次，并且只有当你当前位于该窗口或之前时。 

任务是确定获得文档 m−1 所需执行的程序的最少数量，或者报告这是不可能的。 

这些限制表明存在两种不同的制度。 在最困难的情况下，窗口和文档的数量都可能高达一百万，因此任何尝试显式模拟所有可到达文档集或每个窗口重复重新计算可达性的解决方案都会太慢。 即使是 O(nm) 推理也是完全不可行的，而且如果需要复杂的更新，即使是具有大量文档结构的 O(n log n) 推理也是有风险的。 

重要的结构约束是每个窗口在文档之间恰好贡献一个有向边，并且必须按顺序处理边。 这建议采用单线性通道解决方案，其中每条边都被考虑一次。 

当仅考虑“文档图中的最短路径”时，就会出现微妙的失败案例。 例如，如果忽略排序：

 输入：```
3 4
0 2
2 1
1 3
```简单的最短路径解释立即产生 0 → 2 → 1 → 3，成本为 3，这在这里是正确的。 但是，如果我们重新排序边：```
3 4
2 1
0 2
1 3
```简单的图视图仍然会看到相同的边，但执行顺序很重要：边 2 → 1 出现在我们获得 2 之前，因此无法使用它。 任何忽略窗口顺序的方法都会高估可达性，并且可能错误地声称不可能性或低估步骤。 

核心困难在于可达性取决于文档状态和处理的窗口的前缀。 

## 方法

 强力策略将逐个窗口模拟流程，同时维护我们当前持有的全套文档。 在每个窗口 i，如果我们有文档 a_i，我们可以选择应用转换并将 b_i 添加到我们的集合中。 这直接符合规则并且是正确的，因为它明确尊重顺序和约束。 

然而，这种简单的模拟变得昂贵，因为文档集可以增长到 O(m) 大小，并且每个窗口都可能触发对此增长集的检查。 在最坏的情况下，我们执行 O(nm) 成员资格检查或更新，当 n 和 m 都达到一百万时，这远远超出了可接受的限制。 

关键的观察结果是，我们实际上并不关心整套文档；我们关心的是所有文档。 我们只关心到达每个文件所需的最少程序数量。 一旦文档在 k 步中变得可达，它就永远保持可达，因为文档永远不会丢失，并且未来的操作仅取决于存在，而不是时间。 

这允许我们将整个演化状态压缩到单个数组 dist 中，其中 dist[x] 表示获取文档 x 所需的最少过程数。 当我们处于转换 a_i → b_i 的窗口 i 时，如果 a_i 已经可以通过 dist[a_i] 到达，那么我们可以将 dist[b_i] 改进为 dist[a_i] + 1。排序约束自然受到尊重，因为使用窗口 i 的任何路径只能依赖于较早的窗口，这些窗口在计算 dist[a_i] 时已经被处理。 

因此，问题简化为边缘上的单个从左到右松弛，就像 DAG 中的最短路径一样，其中边缘按拓扑顺序给出。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 文档集的强力模拟 | O(纳米) | O(米) | 太慢了 |
 | 订购 DP 放松 | O(n) | O(米) | 已接受 |

 ## 算法演练

 我们按照给定的顺序处理窗口，同时保留获取每个文档所需的已知程序数量。 

1. 初始化一个大小为 m 的数组 dist，并将所有值设置为无穷大，但 dist[0] = 0 除外，因为我们从已经可用的文档 0 开始。 
2. 按顺序从 1 到 n 迭代窗口。 在窗口 i 处，读取 (a_i, b_i) 对，这意味着我们可以花费一个过程将 a_i 转换为 b_i。 
3. 如果 dist[a_i] 仍然无穷大，则意味着使用任何早期窗口序列都无法实现文档 a_i，因此该窗口无法有意义地使用，我们跳过它。 
4. 否则，我们尝试通过设置 dist[b_i] = min(dist[b_i], dist[a_i] + 1) 来放松 b_i 的状态。 这对应于使用该窗口作为到达 b_i 的有效过程序列的最后一步。 
5. 处理完所有窗口后，答案是dist[m−1]。 如果仍为无穷大，则输出不可能。 

关键思想是，每个有效的过程序列都对应于按递增索引顺序选择窗口子序列，并且此 DP 确保我们考虑所有此类子序列，同时始终仅存储每个文档的最佳成本。 

### 为什么它有效

 不变的是，在处理前 i 个窗口之后，dist[x] 存储仅使用直到 i 的窗口获取文档 x 所需的最少过程数。 任何产生 x 并在前 i 个窗口内结束的有效序列必须以某个产生 x 的窗口 j ≤ i 结束，并且 DP 松弛确保在处理窗口 j 时准确应用转换。 由于较早的窗口在考虑较晚的窗口之前已完全解决，因此未来的信息无法以违反顺序的方式追溯性地改进较早的转换。

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    INF = 10**18
    
    for _ in range(t):
        n, m = map(int, input().split())
        dist = [INF] * m
        dist[0] = 0
        
        for _ in range(n):
            a, b = map(int, input().split())
            if dist[a] != INF:
                nd = dist[a] + 1
                if nd < dist[b]:
                    dist[b] = nd
        
        if dist[m - 1] == INF:
            print("Imposible")
        else:
            print(dist[m - 1])

if __name__ == "__main__":
    solve()
```实现直接遵循松弛思想。 数组 dist 压缩所有可达状态，避免对文档集进行任何显式跟踪。 检查 dist[a] != INF 是必不可少的，因为它确保我们仅在使用早期窗口已经实现其必备文档时才使用窗口。 

更新步骤 dist[b] = min(dist[b], dist[a] + 1) 在到达同一文档的多种可能方式中强制执行最优性。

 ## 边缘情况

 常见的边缘情况是，唯一可用的路径需要使用在其必备文档可访问之前出现的窗口。 例如：

 输入：```
3 3
1 2
0 1
```处理表明窗口 1 → 2 最初不能使用，因为 dist[1] 出现时是无限的。 稍后，当处理 0 → 1 时，我们更新 dist[1]，但我们不会重新访问之前的窗口。 这是正确的，因为任何有效序列都必须遵循窗口顺序，因此在 0 → 1 之前使用 1 → 2 本质上是不可能的。 该算法自然地通过仅允许前向处理来强制执行此约束，从而产生正确的结果。
