 ## 解决方案
 ## 问题理解

 我们正在使用一个简单的电话目录，它存储一个人的姓名和电话号码之间的关联。 系统接收一系列操作，更新存储的姓名号码或询问与给定姓名关联的当前号码。 任务是模拟这些操作并为每个查询返回正确的结果。 

每个输入操作要么是从字符串键到数值的映射的插入或更新，要么是检索给定键的值的请求。 如果之前未添加过名称，则对其进行查询应返回该名称不存在，通常由特殊值（例如“未找到”）表示。 

这些约束意味着操作数量可能足够大，以至于扫描每个查询的所有先前存储条目的任何解决方案都会太慢。 在最坏的情况下，线性搜索每次查找的基于列表的简单方法会降低到二次时间，这无法扩展。 

主要的边缘情况出现在以下情况：同一个名称被多次更新、查询引用从未插入过的名称以及对同一个名称进行多次重复查询时。 例如，如果操作是插入“alice 123”，插入“alice 456”，然后查询“alice”，则正确答案是“456”，因为稍后的更新会覆盖较早的值。 附加条目而不替换旧条目的简单方法会错误地返回第一个值或需要搜索所有出现的值。 

另一个边缘情况是查询丢失的键，例如在未执行插入时查询“bob”。 正确的输出必须明确反映缺席情况，而不是返回 0 这样的默认数值，如果 0 也是有效的电话号码，则可能会产生误导。 

## 方法

 强力解决方案会将所有操作存储在成对列表中，并且对于每个查询，向后扫描列表以查找该名称的最新分配。 这是有效的，因为最近的更新决定了当前值。 然而，在最坏的情况下，有n个操作并且每个操作都是一个查询，每个查询可能扫描O(n)个条目，导致总体时间为O(n^2)。 对于大输入量，这变得不切实际。 

关键的观察是问题的结构不需要历史重建。 在任何时候，只有每个名称的最新值才重要。 这使我们能够将所有先前的更新压缩为单个当前状态。 哈希表（字典）通过将每个名称直接映射到其最新的电话号码来自然地支持这一点。 插入和更新变成简单的覆盖，查询变成直接查找。 

这将整个问题简化为通过高效的平均 O(1) 操作来维护可变键值存储。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（扫描每个查询的历史记录）| O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 哈希映射（字典）| O(n) 平均 | O(n) | 已接受 |

 ## 算法演练

1. 初始化一个空哈希映射来存储姓名到电话号码的映射。 该结构代表电话簿在任何时刻的当前状态。 
2. 按顺序读取输入中的每个操作。 每个操作要么是更新，要么是查询，我们按照它们出现的顺序处理它们，因为后面的操作依赖于前面的更新。 
3. 如果操作是插入或更新，则存储或覆盖哈希映射中的映射。 覆盖至关重要，因为只有最新的名称号码才有效。 
4. 如果操作是查询，则检查该名称是否存在于哈希映射中。 如果是，则输出存储的数字； 否则输出一个哨兵值，例如“未找到”。 
5. 继续，直到处理完所有操作，确保每个查询都反映之前发生的所有更新的状态。 

### 为什么它有效

 在每个时间点，哈希映射都包含每个名称的一个条目，对应于迄今为止看到的最新更新。 这形成了一个不变量：在处理前 k 个操作之后，该映射表示这些操作的正确电话目录状态。 更新通过覆盖过时的值来保持不变性，查询不会修改结构，从而保持正确性。 由于每个操作都只处理一次，并且不需要最新值之外的历史信息，因此最终答案必须与所需的行为相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    phone = {}

    q = int(input().strip())
    for _ in range(q):
        parts = input().split()
        if not parts:
            continue

        if parts[0] == "add":
            name = parts[1]
            number = parts[2]
            phone[name] = number

        elif parts[0] == "find":
            name = parts[1]
            if name in phone:
                print(phone[name])
            else:
                print("not found")

if __name__ == "__main__":
    solve()
```该解决方案维护一个名为`phone`它存储每个名称的最新号码。 对于每一个`add`操作时，它直接分配值，覆盖任何先前的条目。 对于每一个`find`操作时，它在字典中执行恒定时间查找并打印存储的数字或`"not found"`。 

关键的实现细节是Python字典的覆盖行为，这自然符合新更新替换旧更新的要求。 另一个微妙的点是显式处理丢失的键而不是假设默认值。

 ## 边缘情况

 对于同一名称的重复更新，该算法始终替换字典中的先前值。 例如，插入“alice 1”，然后插入“alice 2”会导致最终状态为`alice → 2`，任何查询都返回 2。覆盖行为是直接的，不需要任何额外的逻辑。 

对于任何插入之前的查询，字典是空的，因此每次查找都无法通过成员资格检查。 像这样的查询`find unknown`正确返回`"not found"`因为该算法显式检查存在性而不是假设默认数值。 

对于更新和查询的混合序列，字典表示处理所有先前操作后的状态的不变性确保了每一步的正确性。
