 ## 解决方案
 ## 问题理解

 我们得到了几个二进制字符串，我们可以将它们以任何顺序连接成一个长的二进制字符串。 一旦连接起来，我们就计算通常意义上的反转：一对位置，其中`1`出现在 a 之前`0`。 

任务不仅仅是计算固定字符串的反转，而是选择输入字符串的顺序，以便最终的串联产生尽可能少的此类反转。 

在单个字符串内部，字符的相对顺序是固定的，因此其内部反转的贡献是不可避免的。 真正的自由来自于不同字符串的交互方式：将一个字符串放在另一个字符串之前可以在任何时候创建额外的反转。`1`前面的字符串在 a 之前结束`0`在后面的字符串中。 

这些限制意味着所有字符串的总长度最多为一百万。 这排除了任何尝试字符串的所有排列甚至字符串数量的二次排列的解决方案。 基于排序的方法或对串联的线性扫描是必要的。 

一种简单的方法会尝试字符串的每种排列并每次计算反转计数。 即使忽略重新计算成本，这也是不可能的，因为最多 10^6 的字符串将使阶乘增长完全不可行。 即使字符串较少，重新计算每个排列的反转计数也需要重复扫描所有字符，从而导致 O(n!·total_length) 之类的结果。 

第二个天真的想法是以任意顺序连接并计算一次反转。 这会失败，因为顺序会严重改变跨字符串反转。 

当字符串只有 1 或只有 0 时，会出现微妙的边缘情况。 例如，`"111"`和`"000"`根据顺序，行为有很大不同。 如果`"111"`出现在之前`"000"`，每对都贡献一个反转，而相反则不产生任何反转。 任何正确的策略都必须抓住这种不对称性。 

## 方法

 我们将反转计数分为两部分：每个字符串内的反转和字符串之间创建的反转。 

无论订购如何，内部零件都是固定的。 对于每个字符串，我们可以计算有多少对`(1 before 0)`在其长度上以线性时间直接发生在其内部。 

困难的部分是跨弦反转。 假设我们将字符串 A 放在字符串 B 之前。`1`A 与每个形成反演`0`因此，将 A 排序在 B 之前的贡献为：```
cost(A before B) = ones(A) * zeros(B)
```如果我们交换它们，成本就变成：```
cost(B before A) = ones(B) * zeros(A)
```因此，排序问题变成了选择一种排列，以最小化成对交换相关成本的总和。 

这种结构与具有比较规则的调度或排序问题完全相同。 对于两个字符串 A 和 B，当出现以下情况时，我们将 A 放在 B 之前：```
ones(A) * zeros(B) <= ones(B) * zeros(A)
```重新排列给出了稳定的排序条件：```
ones(A) / zeros(A) <= ones(B) / zeros(B)
```（当零为零时要小心处理）。 

所以通过对字符串按比例排序得到最优排列`ones / zeros`按升序排列，对字符串有零个零的边缘情况进行特殊处理。 

排序后，我们从左到右扫描，保持有多少个`1`s已经出现了。 当我们放置一个新的字符串 B 时，每个`0`B 内部与所有先前的反转创建一个反转，贡献：```
ones_so_far * zeros(B)
```我们还添加了它的内部反转。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（所有排列）| O(n!·L) | O(n!·L) | O(L) | 太慢了|
 | 最优（排序+线性扫描）| O(L log n) | O(L log n) | O(L) | 已接受 |

 ## 算法演练

 我们首先通过提取两个值来预处理每个字符串：它包含多少个 1 和它包含多少个 0。 在进行此扫描时，我们还通过跟踪每个 1 右侧剩余的零个数来计算其内部反转计数。 

接下来，我们对所有字符串进行排序。 排序键是比率除以零。 如果一个字符串有零个零，那么它会被放置在所有仍然有零的字符串之后，因为它的比率表现得像无穷大，并且它不应该在最佳排序中排在前面。 

排序后，我们按该顺序迭代字符串。 我们会持续统计迄今为止出现的数量。 对于每个字符串，我们添加两个贡献：已经为该字符串计算的内部反转，以及由它的零与所有先前的零配对创建的交叉反转。 

然后我们通过添加当前字符串中的个数来更新正在运行的计数器。 

它之所以有效，是因为任何两个字符串之间的交叉贡献仅取决于它们的 1 和 0 的聚合计数。 相邻字符串之间的任何交换都会通过精确比较来改变答案`ones(A)*zeros(B)`和`ones(B)*zeros(A)`。 这使得问题相当于通过一致比较器进行排序，这保证了一旦不存在该排序规则的相邻反转，则任何全局重新排列都无法提高总成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def inv_inside(s: str) -> int:
    zeros = 0
    inv = 0
    # count inversions of type 1 before 0
    for c in reversed(s):
        if c == '0':
            zeros += 1
        else:
            inv += zeros
    return inv

def key(item):
    ones, zeros, _ = item
    if zeros == 0:
        return (1, 0)  # treat as largest possible ratio
    return (0, ones / zeros)

def solve():
    n = int(input())
    items = []

    for _ in range(n):
        s = input().strip()
        ones = s.count('1')
        zeros = len(s) - ones
        items.append((ones, zeros, inv_inside(s)))

    items.sort(key=key)

    ones_so_far = 0
    ans = 0

    for ones, zeros, internal in items:
        ans += internal
        ans += ones_so_far * zeros
        ones_so_far += ones

    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先使用反向扫描来隔离每个字符串的内部反转结构，该反向扫描计算每个字符串右侧有多少个零。 这避免了每个字符串的任何二次行为。 

排序函数对导出的排序规则进行编码。 通过为零零的字符串分配最大键，将其强制到末尾。 对于所有其他字符串，1 与 0 的比率决定位置。 

最后的扫描使用 1 的前缀和来累积跨字符串反转，它准确地表示有多少个`1`每个`0`在当前字符串中将与之交互。

 字符串`"101"`有 1 = 2，0 = 1，内部反转 = 1

 按个/零位置排序`"101"`首先，因为它的比率为 2，而其他的则为零，然后再进行。 

排序后：

 | 3 | 11 | 11 3 | 0 | 0 | 0 | 1 |

 最终答案为1，与样本相符。 

该迹线表明内部反演被正确隔离，并且交叉贡献仅取决于累积的贡献。

 ## 边缘情况

 仅由 1 组成的字符串没有内部反转，并且在放置在任何位置时不会创建未来的反转，因为它在交叉公式中贡献了 0 = 0。 由于此类字符串的无限比率行为，该算法正确地将其推到末尾，并且它们的位置不会影响总数。 

仅由零组成的字符串也没有内部反转，但如果放置得较早，则会对交叉反转产生很大影响。 由于它的 0 > 0 且 1 = 0，因此它的比率为 0，因此它自然出现在排序顺序的开头，从而最大限度地减少其 0 与之前的 0 的接触。 

具有相同的 1/0 比率的字符串在交换下会产生相同的排序成本。 该算法允许它们之间的任何顺序，并且前缀和公式确保等比交换不会改变最终答案，因为`ones(A)*zeros(B) == ones(B)*zeros(A)`在这种情况下成立。
