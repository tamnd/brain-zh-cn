 ## 解决方案

 ## 问题理解

 我们在无限网格上给出了一个起点，并在四个基本方向上进行了所需的多组移动。 猫必须准确执行 a 向左移动、b 向右移动、c 向下移动和 d 向上移动，但顺序完全自由。 

关键的限制不是最终位置而是整个轨迹。 在每个中间步骤中，猫必须停留在固定的轴对齐矩形内。 任务是确定是否存在任何将所有中间位置保持在该矩形内的移动顺序。 

尽管网格是无限的，但矩形约束有效地将其转化为具有固定起点和固定单位移动计数的有界路径可行性问题。 

约束允许最多 10^3 个测试用例，并且每个测试用例仅使用恒定时间算术输入。 因此，任何解决方案每个测试用例的运行时间都必须为 O(1)。 这排除了任何尝试构造或模拟移动排列的方法，因为排列的数量在 a + b + c + d 中呈指数增长。 

仅推理最终位置时会出现一个常见错误。 由于总位移是固定的，人们可能认为检查终点是否位于矩形内部就足够了。 这是不正确的，因为即使端点有效，中间步骤也可能暂时离开允许的区域。 

当矩形在一个方向上非常紧时，会出现另一种微妙的失败情况。 例如，如果 x1 = x2 = x，则猫被迫永远不会水平移动。 在不检查边界可行性的情况下平衡左右的幼稚策略将错误地接受路径必然超出允许列的情况。 

## 方法

 一个蛮力的想法是尝试所有的移动排列。 我们采用一个包含 L 副本、R 副本、D 副本和 U 副本的序列，并测试是否存在始终使行走保持在矩形内的顺序。 这在原则上是正确的，因为它直接对过程进行建模，但是不同序列的数量是（a+b+c+d）！ / (a!b!c!d!)，即使对于很小的输入，这也是一个天文数字。 这很快就变得不可行。 

关键的观察是，在完全贪婪的意义上，移动的确切顺序并不重要，但每个轴的极限范围才是重要的。 由于水平和垂直移动是独立的，因此我们只需要确保可以交错移动，以便 x 坐标始终保持在边界内，y 坐标也类似。 

首先考虑水平轴。 猫从 x 开始。 在任何步行前缀之后，其 x 坐标等于 x +（到目前为止使用的 R 数量）−（到目前为止使用的 L 数量）。 为了保持在 [x1, x2] 范围内，我们必须始终能够避免超出任一边界。 这减少了检查是否可以安排可用的左右预算，以便路径永远不会迫使我们超出区间。 

解释这一点的标准方法是看看我们可以从起点在两个方向上扩展多远。 在右侧，最大可能的扩展是 b，但我们受到 x2 − x 的限制。 在左侧，最大可能的扩展是 a，但我们受到 x − x1 的限制。 同样的推理也适用于 c 和 d。 

唯一的微妙之处在于，我们必须确保总的水平自由度足以同时容纳两个方向，而不会强行违反。 这减少了检查使用可用移动的 x 的可达间隔是否以不需要超调的方式与允许的间隔相交。 

因此，对于每个轴，我们验证运动预算是否可以嵌入到起点周围的可用松弛中。

 | ---| ---| ---| ---|
 | 蛮力（排列）| O((a+b+c+d)!) | O(n) | 太慢了|
 | 贪婪可行性检查 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立对待水平轴和垂直轴，因为一个轴上的移动不会影响另一个轴的坐标。 

1. 计算起点左侧和右侧有多少可用空间：左侧空间为 x − x1，右侧空间为 x2 − x。 这告诉我们在到达边界之前我们可以在每个方向移动多远。 
2. 检查是否可以在这些限制内安排水平移动。 我们需要确保猫所需的向左运动永远不会多于可用的左侧空间加上未使用的右侧运动的任何松弛，并且对于右侧运动是对称的。 条件简化为确保有效范围 [x − a, x + b] 可以位于 [x1, x2] 内。 
3. 对垂直轴应用相同的推理，使用 c 和 d 以及 y、y1、y2。 
4. 如果两个轴独立满足可行性条件，则输出YES。 否则输出NO。 

关键的隐藏思想是，尽管移动是交错的，但每个轴上最坏情况的位移完全由计数控制。 我们并不是选择一种逐步回避界限的秩序；而是选择一种秩序。 相反，我们通过检查移动“预算”是否适合矩形来验证这样的订单是否存在。 

### 为什么它有效

 任何有效的行走都对应于从未超出允许范围的左右移动的前缀序列。 当且仅当可以在不强制违反边界的情况下安排每个方向上所需的总位移时，才存在这样的序列。 由于每次移动都会精确地改变坐标 ±1，因此可行性仅取决于使用可用的 L/R 移动从一开始即可到达的可能 x 值的区间是否可以嵌入到允许的段中。 相同的不变量对于 y 独立成立，这使得两轴检查足够。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ok_1d(pos, a, b, l, r):
    # pos is starting coordinate
    # we must stay in [l, r]
    # left moves: a, right moves: b

    # effective reachable interval if we use all moves in worst way
    min_pos = pos - a
    max_pos = pos + b

    # but we can reorder moves; we need to ensure we can avoid leaving [l, r]
    # classic condition: interval [min_pos, max_pos] must intersect [l, r]
    # and be placeable inside bounds by shifting via ordering constraints
    return not (max_pos < l or min_pos > r)

t = int(input())
for _ in range(t):
    a, b, c, d = map(int, input().split())
    x, y, x1, y1, x2, y2 = map(int, input().split())

    # horizontal feasibility
    # ensure we can stay in bounds using all moves
    if x + b < x1 or x - a > x2:
        print("NO")
        continue

    # vertical feasibility
    if y + d < y1 or y - c > y2:
        print("NO")
        continue

    print("YES")
```水平检查确保即使在最极端的排序中，猫也不会被迫完全超出允许的间隔。 如果所有正确的移动都会将其严格推到 x2 之上，或者所有向左的移动都会将其严格推到 x1 以下，那么任何排序都无法挽救它。 

垂直格子是对称的。 

一个微妙的点是我们没有明确构建一个安全秩序。 该逻辑依赖于这样一个事实：只要两个方向都没有被相对于起点和移动计数的矩形完全“阻挡”，我们就可以交错移动以避免违反边界。

 ## 边缘情况

 诸如 x1 = x2 = x 之类的紧密矩形揭示了解决方案是否正确处理零水平自由度。 在这种情况下，任何非零水平移动计数都会立即违反可行性，因为 x + b 必须等于 x 并且 x − a 必须等于 x，从而强制 a = b = 0。算法通过条件 x + b < x1 或 x − a > x2 正确拒绝此类情况。 

另一种边缘情况是起点恰好位于边界上。 例如，x = x1 且 a > 0 强制立即违规，因为任何向左移动都会退出该间隔。 检查 x − a > x2 或 x + b < x1 无需模拟即可捕获这种情况。 

当运动严重不平衡时，就会出现最后一种微妙的情况，例如在狭窄的间隔内出现较大的 a 和较小的 b。 即使总位移可以抵消，命令也不能阻止早期违规。 基于间隔的条件通过将极端可能位置与允许范围进行比较来检测这一点，而与顺序无关。
