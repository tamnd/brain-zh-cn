 ## 解决方案

 ## 问题理解

 我们有两堆单位，用整数描述$a$和$b$。 我们可以一步选择一个正整数$x$并应用两个变换之一：要么我们减去$x$从$a$和$2x$从$b$，或者我们减去$2x$从$a$和$x$从$b$。 我们可以重复这些动作任意多次，选择不同的值$x$每次。 

问题是是否有可能同时将两个堆完全清零，而不使值变为负值。 

就测试用例的数量而言，约束很小，但是$a$和$b$可以大到$10^9$。 这就排除了任何试图逐步应用操作的模拟，因为减少的幅度太大，并且选择的空间也很大。$x$在正整数上连续。 任何正确的解决方案都必须将问题减少到每个测试用例的恒定时间检查。 

一个微妙的问题源于选择不同价值观的自由$x$。 天真的直觉可能会建议先贪婪地减去较大的值，或者总是使用$x=1$，但这些方法失败了，因为操作不是独立的单元步骤； 每个操作以固定的比例耦合两个变量，因此局部贪婪决策可能会破坏全局可行性。 例如，从$(1,2)$，仅贪婪地应用$(x,2x)$即使存在使用两种操作类型的有效序列，操作也会立即失败。 

核心困难在于我们不是分配固定数量的单元操作，而是以任意缩放组合两个向量变换。 

## 方法

 如果我们忽略效率，我们可以尝试从重复应用操作并探索所有可能的序列的角度来思考。 每次操作都会减少该对$(a,b)$通过任一$x(1,2)$或者$x(2,1)$。 强力搜索将根据操作类型和可能的值进行分支$x$，试图达到$(0,0)$。 即使我们离散化$x$对于单位步骤，状态空间增长得非常快，因为两个坐标都可以大到$10^9$。 这使得任何基于搜索的方法都不可行。 

关键的观察结果是操作顺序并不重要。 只有每种操作类型的总贡献很重要。 假设我们聚合所有类型的操作$(1,2)$计入总金额$p$，以及所有类型的操作$(2,1)$计入总金额$q$。 然后问题就变成了解决一个线性系统，其中这些聚合贡献必须完全匹配$a$和$b$。 

这将问题从推理序列简化为求解具有非负约束的两个线性方程。 一旦我们这样做了，结构就会变得足够坚固，可以在恒定的时间内检查可行性。

 ## 算法演练

 我们根据每种操作类型的累计使用总量重新解释操作。 我们不考虑个人的行动，而是将所有人分组$(1,2)$-类型减少一起和所有$(2,1)$一起减少类型。 

1. 让$p$表示类型操作贡献的总金额$(1,2)$， 和$q$表示类型操作贡献的总金额$(2,1)$。 这是有效的，因为通过拆分来缩放操作$x$分成更小的部分并不会改变净效果。 
2. 表达最终的减少量$a$和$b$按照$p$和$q$。 总减少量为$a$变成$p + 2q$，而总减少量为$b$变成$2p + q$。 为了达到零，我们要求系统：$$p + 2q = a, \quad 2p + q = b$$3. 求解该系统以了解可行性条件。 消除变量给出$3p = 2b - a$和$3q = 2a - b$。 这立即意味着两个表达式必须为非负且能被 3 整除，整数解才存在。 
4. 通过添加方程，出现一个更简单的必要条件：$3(p+q) = a + b$， 所以$a + b$必须能被 3 整除。这个条件已经限制了大多数不可能的情况。 
5. 非负约束转化为几何可行性：两个坐标相对于另一个坐标都不能太小。 具体来说，一个变量的减少量绝不能超过组合两种操作类型所能提供的减少量。 
6. 结合这些条件可以得到一个紧凑的检查：总和必须能被 3 整除，并且不能被 3 整除。$a$也不$b$可以超过对方的两倍。 

### 为什么它有效

 每次操作都会减少总量$a + b$正是通过$3x$，因此总和在所有操作中模 3 不变。 这使得能被 3 整除成为一个硬性要求。 一旦满足该条件，整个过程就会减少到在两个固定向量之间分配总减少量$(1,2)$和$(2,1)$。 这些向量形成二维基础，因此任何可到达的端点都精确对应于它们的非负组合。 不等式确保这种组合不需要负系数，这对应于反转操作，这是不允许的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b = map(int, input().split())

        if (a + b) % 3 != 0:
            print("NO")
            continue

        if max(a, b) > 2 * min(a, b):
            print("NO")
            continue

        print("YES")

if __name__ == "__main__":
    solve()
```代码直接实现了导出的可行性条件。 第一个检查强制执行模 3 不变量，因为每个操作都精确删除$3x$总单位数。 第二个检查强制两个变量与另一个变量相比都不会太大，这将导致无法使用允许的操作比率来平衡减少。

 我们追踪两个代表性案例的逻辑。

 | 开始 | 6 | 9 | 0 | 9 ≤ 12 | 是 |

 总和可被 3 整除，并且两个值都不会超出允许的因子 2。这对应于两种操作类型的有效分解，因此答案为“是”。 

### 示例 2：(1, 1)

 | 步骤| 一个 | 乙| a+b 模 3 | 最大条件| 决定|
 | ---| ---| ---| ---| ---| ---|
 | 开始 | 1 | 1 | 2 | 1 ≤ 2 | 否 |

 尽管这些值很小且平衡，但总和不能被 3 整除。由于每次运算都会从总和中删除 3 的倍数，因此不可能达到零。 

第二个例子表明，仅仅平衡是不够的； 模块化约束是真正的限制因素。

 ## 边缘情况

 一个常见的陷阱是仅依赖比率条件而不检查模约束。 例如，$(2,4)$满足平衡直觉，但如果在类似变体中忽略总和条件，则会失败； 在这里它确实有效，因为整个系统是一致的。 正确的处理方法始终是同时执行这两种约束，因为一个约束是全球保护，另一个约束是定向减排的可行性。
