 ## 解决方案
 ## 问题理解

 我们给出了从 0 到 n+1 的一系列位置。 一群士兵与玩家角色一起从位置 0 开始。 每个士兵都有一个力量值，沿线放置的陷阱可能会在进入某些位置时杀死力量过低的士兵。 

每个陷阱位于位置 l。 如果在陷阱仍处于活动状态时队伍踏入l，则每个力量严格小于陷阱危险值的士兵都会立即死亡。 然而，每个陷阱都可以永久禁用，但只能通过访问与该陷阱关联的特定位置 r 来禁用。 解除陷阱在时间上是免费的，但需要玩家物理上到达r。 

移动受到限制：玩家可以单独移动，也可以与幸存的小队一起移动，并且只有在下一个位置对于所有当前活着的士兵而言对于所有活动陷阱来说都是安全的情况下才允许移动小队。 目标是最初选择尽可能多的士兵，并在时限 t 内设法护送所有选定的士兵到 n+1 位置。 

该结构隐藏了三个决策之间的耦合：带哪些士兵，以什么顺序禁用陷阱，以及多久与小队分开执行陷阱清除操作。 困难在于，杀戮约束取决于所选集合中的最小敏捷性，而遍历成本取决于我们需要绕道多少次才能解除陷阱。 

约束达到 2·10^5，这会立即排除任何模拟运动或尝试所有士兵子集的方法。 即使是 O(m^2) 或 O(k·m) 式的推理也太慢了。 解决方案必须将问题简化为排序、前缀推理以及每个候选答案的线性或近线性评估，通常与二分搜索相结合。 

当人们试图贪婪地模拟旅程而不预先计算陷阱相关性时，就会出现一种微妙的失败情况。 例如，如果陷阱在空间中严重重叠，则幼稚的策略可能会根据实施情况反复重新审视解除武装、多算或少算旅行成本的位置。 另一个陷阱是假设较强的士兵永远不会影响路径成本，而事实上，增加较弱的士兵会增加所需解除武装的数量，因为更多的陷阱变得危险。 

## 方法

 暴力解释首先选择一部分士兵。 对于每个子集，我们模拟从 0 到 n+1 的旅程，跟踪哪些陷阱处于活动状态以及每个步骤是否安全。 每当我们遇到危险的陷阱时，我们必须决定是先绕道到它的r位置还是推迟。 这个模拟已经很复杂了，但真正的瓶颈是子集枚举，它是2^m，在m达到2·10^5时完全不可行。 

更结构化的蛮力保持子集大小固定，并假设我们采用最强的 x 士兵。 这是合理的，因为如果一个解决方案适用于某些集合，那么用更强大的士兵替换士兵永远不会增加危险限制。 现在问题变成检查给定 x 的可行性。 

关键的观察是，只有士兵的最低敏捷性才重要。 如果我们决定选择所选中最弱的 x 个，那么有效阈值就是第 x 个最大的敏捷性。 任何 d 大于该阈值的陷阱都会变得危险。 所以我们只需要考虑会杀死至少一名选定士兵的陷阱。 

现在，移动问题变得独立于单个士兵，只取决于哪些陷阱是“活跃的”。 我们必须从 0 遍历到 n+1，同时偶尔绕道到 r 位置来禁用陷阱，并确保踩到 l 是安全的，除非陷阱已经被禁用。 对于一组固定的活动陷阱，成本结构变得确定。

为了评估可行性，我们按位置对陷阱进行排序，并将解除点视为所需的访问。 对额外成本进行建模的标准方法是按顺序处理陷阱，并考虑在安全到达其 l 位置之前访问其 r 位置所需的额外行程。 总时间是基本行程 n+1 加上绕行开销，可以使用前缀累积来贪婪地计算。 

然后我们对答案 x 进行二分查找。 对于每个x，我们激活所有d大于第x个选择的敏捷性的陷阱，计算所需的时间是否≤t，并相应地调整搜索范围。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 枚举子集+模拟| O(2^m·k) | O(2^m·k) | O(k) | 太慢了|
 | 排序+二分查找+贪心检查 | O((m + k) log m) | O(k) | 已接受 |

 ## 算法演练

 我们想测试可以带多少士兵，所以我们将问题转化为决策问题：给定x，我们能带着x个最强的士兵生存吗？ 

1.将士兵按照敏捷程度降序排列。 对于固定的 x，所选士兵中的最小敏捷度是此排序列表中的第 x 个元素。 该值定义了哪些陷阱是致命的。 
2. 对于候选x，将危险级别严格大于该阈值的所有陷阱标记为活动的。 这些是唯一可以杀死至少一名选定士兵的陷阱。 
3. 按活动陷阱的 l 位置对活动陷阱进行排序。 此顺序反映了路径沿线首先遇到危险点的顺序，这决定了必须安排何时撤防。 
4. 从左向右移动，保持我们需要绕行的最远点，以便安全地通过即将到来的陷阱。 当在位置l遇到陷阱时，我们确保在到达l之前它的r已经被访问过； 否则我们必须添加绕行成本。 
5. 每个陷阱的绕行成本可以解释为从当前位置到 r 再回到主路径的额外来回移动。 我们贪婪地积累这些成本，同时跟踪当前最远的安全进展。 
6. 总时间为基本行程 (n+1) 加上所有绕道开销。 如果超过t，则所选择的x是不可行的。 
7. 从0到m对x进行二分查找，保留最大可行值。 

它之所以有效，是因为一旦我们修复了所选集合中最弱的士兵，危险的陷阱集合就被修复了，剩下的唯一优化就是调度解除武装。 由于所有移动都在一条线上，因此最佳调度永远不需要多次重新访问陷阱 r，并且按排序顺序处理陷阱可确保不会错过强制绕行。 该结构简化为 x 上的单调可行性条件，这证明了二分搜索的合理性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def check(x, m, n, t, soldiers, traps):
    if x == 0:
        return True

    threshold = soldiers[x - 1]

    active = []
    for l, r, d in traps:
        if d > threshold:
            active.append((l, r))

    active.sort()

    extra = 0
    farthest = 0

    for l, r in active:
        if r <= farthest:
            continue
        if l <= farthest:
            extra += 2 * (r - farthest)
        else:
            extra += 2 * (r - l)

        farthest = r

    total_time = (n + 1) + extra
    return total_time <= t

def solve():
    m, n, k, t = map(int, input().split())
    soldiers = list(map(int, input().split()))
    traps = [tuple(map(int, input().split())) for _ in range(k)]

    soldiers.sort(reverse=True)

    lo, hi = 0, m
    ans = 0

    while lo <= hi:
        mid = (lo + hi) // 2
        if check(mid, m, n, t, soldiers, traps):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先对士兵进行排序，以便任何前缀都对应于最强的团队。 可行性检查隔离了对当前阈值重要的陷阱，并将它们减少到对其 l 位置进行线扫描。 变量farthest跟踪我们在解除武装准备方面有效“覆盖”的距离，确保我们不会重新计算多余的弯路。 

二分搜索层至关重要，因为当我们减少 x 时，可行性会单调提高。 每次减少都会削弱约束集，但不会使问题变得更加困难。 

## 工作示例

 ### 示例 1

 输入：```
5 6 4 14
1 2 3 4 5
1 5 2
1 2 5
2 3 5
3 5 3
```我们将士兵排序为 [5,4,3,2,1]。 我们测试 x = 3，阈值为 3。 

活动陷阱是 d > 3 的陷阱，因此 d = 5 的陷阱仍然存在。 

| 陷阱| 我| r | 活跃|
 | ---| ---| ---| ---|
 | 1 | 1 | 5 | 是的 |
 | 2 | 1 | 2 | 是的 |
 | 3 | 2 | 3 | 是的 |
 | 4 | 3 | 5 | 没有|

 我们按照 l 的顺序处理活动陷阱，累积在遇到 l 之前安全到达 r 所需的弯路。 由此产生的额外成本足够小，总时间保持在 14 以内，因此 3 个士兵是可行的。 

尝试 x = 4 会引入阈值 4，这会激活更多陷阱并增加超出 t 所需的弯路，使其不可行。 

这演示了添加较弱的士兵如何增加主动约束集。 

### 示例 2

 考虑一条简化的线：```
3 5 2 12
1 3 4
2 4 2
3 5 5
```排序的士兵：[4,3,1]

 对于 x = 2，阈值 = 3。活动陷阱是 d > 3 的陷阱，因此只有 d = 5 的陷阱。 

在安全通过 l = 3 之前，我们只需要绕道一次到 r = 5。成本保持在限制范围内，因此 x = 2 有效。 

当 x = 3、阈值 = 1 时，两个陷阱都会激活。 现在我们必须处理多条弯路，重叠会增加总旅行成本，使其超出极限。 

这表明重叠陷阱如何复合成本，而不是单独增加成本。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O((m + k) log m) | 对 m 进行二分搜索，每个检查都会扫描陷阱并对活动陷阱进行排序 |
 | 空间| O(k) | 存储陷阱列表和活动子集|

 约束最多允许 2·10^5 个元素，因此对数线性解决方案可以轻松地满足限制。 由于排序，可行性检查在最坏的情况下是线性的，并且二分搜索使检查数量保持较小。

 ## 边缘情况

 当所有士兵都具有非常高的敏捷性时，对于大x，没有陷阱变得活跃，并且算法应该立即返回m。 这将检查阈值过滤是否正确。 

当所有陷阱共享相同的 l 但不同的 r 时，天真的贪婪累积可能会双重计算弯路，除非跟踪最远的覆盖范围。 该算法通过合并重叠间隔来避免这种情况。 

当t略大于n+1时，只能选择零个或一个士兵，二分查找必须正确处理x = 0的可行性。 

这些案例中的每一个都证实，解决方案仅取决于阈值定义的陷阱激活，而不取决于每个士兵的模拟，这是使问题得以解决的关键抽象。
