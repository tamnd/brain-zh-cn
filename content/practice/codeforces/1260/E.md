 ## 解决方案
 ## 问题理解

 我们有一场淘汰赛$n$参与者，在哪里$n$is a power of two. Each participant has a fixed strength, and in any direct match the stronger boxer always wins unless we have paid a bribe for the weaker one, in which case the weaker boxer is allowed to win that match.

 就配对而言，比赛完全在我们的控制之下。 在每一轮中，我们将剩余的拳击手分成几对，每对产生一个获胜者，获胜者继续前进。 This repeats until a single champion remains. 一位特殊的拳击手是您的朋友，在输入中通过值进行识别$-1$。 目标是确保这位朋友成为最终的获胜者，同时最大限度地减少向其他拳击手支付的总贿赂成本。 

关键的微妙之处在于，贿赂并不是为了让你的朋友在全球范围内变得更强大，而是为了在需要时有选择地强制比赛结果。 由于每一轮的配对都是任意的，我们可以选择你的朋友面对哪些对手以及提前消除哪些潜在威胁。 

约束条件允许$n$最多$2^{18}$，意味着最多 262144 名玩家。 明确考虑所有子集或所有锦标赛树的解决方案是不可行的，因为可能的锦标赛结构的数量呈超指数增长。 任何有效的解决方案都必须压缩状态空间，以便每个拳击手都被处理少量次，最好是对数或线性。 

一个天真的错误是假设我们只需要为所有比朋友更强的拳击手付费，或者排序并贪婪地消除最强的对手就足够了。 这会失败，因为如果我们被迫在错误的阶段面对他们，而没有贿赂足够多的其他人来控制早期的淘汰，那么即使是较弱的拳击手也可能成为问题。 

另一种常见的失败情况是假设朋友必须在决赛中直接击败剩下的最强对手。 这忽略了配对的自由，这使我们能够及早隔离威胁并重塑锦标赛树。 

## 方法

 暴力方法将模拟所有可能的锦标赛结构。 在每个阶段，我们都可以选择配对并递归计算每个可能的获胜者组所需的最小成本。 这很快就会变成指数，因为即使对于单轮$k$玩家的配对数量为$(k-1)!!$，并且每个配对都会导致另一个递归状态。 即使对子集进行记忆，状态的数量也是$O(2^n)$，这是不可能的$n = 2^{18}$。 

关键的观察是我们实际上并没有明确地决定完整的锦标赛树。 相反，我们会决定哪些玩家每轮都能生存下来，从而让朋友活下去。 每个玩家要么被更强大的人淘汰，要么如果被迫参加一场本来可以战胜朋友的比赛，则必须受到贿赂。 

这表明在每个阶段都要考虑“可用的对手”，而不是明确的匹配树。 我们按照强度递增的顺序处理玩家，并保持最佳方式以确保来自一定范围的最多一个“候选威胁”能够生存到更高的级别。 出现的结构是对集合的二元层次结构的贪婪构造：在每个级别，我们可以合并两个组，并决定是否支付费用来中和一个代表或允许其作为未来的对手生存。 

这自然会导致强度域的二进制分解上的DP，其中每个玩家根据他们可以通过多少“锦标赛生存级别”而不会被淘汰而贡献成本。 好友充当主播，所有其他玩家都会根据代价进行评估，以确保他们永远不会达到可以阻止好友的阶段。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解锦标赛模拟|$O(n!)$/ 指数 |$O(n)$| 太慢了|
 | 贪婪分层DP |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将锦标赛解释为$\log_2 n$回合。 每个选手在进入决赛之前都必须被淘汰，我们通过贿赂来控制淘汰。 

我们在生存成本的“级别”上维护一个 DP 数组，其中合并对应于决定哪个对手生存到下一轮以及哪个对手通过贿赂被淘汰。 

1. 明确朋友的立场。 让朋友成为一切决定的根源； 我们给他分配成本为 0，因为我们从不贿赂他。 
2. 对于其他所有拳击手$i$，考虑到如果他们没有被贿赂，他们就会表现得最佳，并且会通过有利的配对来尝试尽可能长时间地生存。 
3. 我们从概念上为每个拳击手分配一个“生存深度”，代表如果不提前淘汰，他们可以生存多少回合。 这是由锦标赛规模决定的，因为任何参与者都可以通过括号进行路由。 
4.我们通过增强实力来处理球员。 这种顺序很重要，因为在任何不受控制的比赛中，较强的球员更难被淘汰并统治较弱的球员。 
5. 我们维持一种结构，在每个“级别”我们只能允许一名未受贿的幸存者。 如果同一层存在两名潜在的幸存者，则必须贿赂（贿赂）其中一名，以防止以后发生冲突。 
6.对于每个拳击手，我们尝试将他们置于尽可能高的水平，以便他们可以安全地间接淘汰。 如果不存在这样的水平，我们就被迫支付他们的贿赂成本。 
7. 贪婪的选择是总是尽可能推迟付款，因为过早行贿会降低以后处理更强玩家的灵活性。 
8. 最终答案是本次安置过程中选择的所有受贿球员的总和。 

关键的不变量是，在处理所有玩家达到给定的强度阈值后，我们在每个锦标赛级别中永远不会有超过一个未受贿的“主动威胁”。 任何违规行为都意味着未来将被迫与朋友或另一个幸存的威胁进行比赛，而没有可用的淘汰路径，这与可行性相矛盾。 因此，每当冲突出现时，贿赂最便宜的必要参与者可以恢复可行性，同时保持最优性，因为延迟贿赂只会减少未来的选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    friend = -1
    for i, x in enumerate(a):
        if x == -1:
            friend = i
            break
    
    dp = []
    cost = 0
    
    for i in range(n):
        if i == friend:
            continue
        dp.append(a[i])
    
    dp.sort()
    
    k = len(dp)
    lvl = 0
    
    import math
    max_level = 0
    tmp = n
    while tmp > 1:
        max_level += 1
        tmp //= 2
    
    import heapq
    
    heap = []
    
    for x in dp:
        heapq.heappush(heap, x)
    
    used = [0] * (max_level + 1)
    
    while heap:
        x = heapq.heappop(heap)
        placed = False
        
        for lvl in range(max_level + 1):
            if used[lvl] == 0:
                used[lvl] = 1
                placed = True
                break
        
        if not placed:
            cost += x
    
    print(cost)

if __name__ == "__main__":
    solve()
```该实施首先隔离了朋友，因为没有任何成本与他们相关。 除贿赂费用外，所有其他拳击手均受到统一待遇。 

我们对贿赂成本进行排序，以确保当冲突发生时，我们总是首先消除最便宜的可用选项，这对于最优性是必要的。 我们还计算锦标赛级别的最大数量，这限制了在强制收敛之前存在多少个独立的“槽位”以供生存。 

贪婪放置在每个级别使用一个简单的占用数组。 每个拳击手都会被分配到最早的可用级别； 如果所有楼层都已被占领，则必须贿赂该拳击手。 这反映了每个级别只能承受一个独立的幸存威胁的想法。

 ## 边缘情况

 一个重要的边缘情况是当朋友已经是最强的拳击手时。 For input like:```
4
1 2 3 -1
```不需要贿赂。 该算法将所有其他玩家分配到可用的锦标赛级别，并且由于没有发生结构冲突，因此不会累积成本。 

另一种情况是存在许多廉价玩家。 例如：```
4
1 1 1 -1
```在这里，所有三个对手都可以被分为不同的级别，并且不需要贿赂。 贪婪的放置确保每个级别都被填充一次，并且由于容量与对手的数量相匹配，因此不会发生溢出。 

一种对比鲜明的边缘情况是，当对手的数量显着超过可用水平时，就会迫使结构重复覆盖并引发贿赂。 在这种情况下，只有当所有层级槽都已被占用时，算法才会正确累积成本，确保通过支付最便宜的剩余可行对手来解决每个强制冲突。
