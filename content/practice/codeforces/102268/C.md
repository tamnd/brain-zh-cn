 ## 解决方案
 ## 问题理解

 我们需要构造两个整数数组`a`和`b`其值根据两种不同的排列进行排序。 排列`p`规定了值的非递减顺序`a`， 尽管`q`规定了值的非递减顺序`b`。 

对于指数`i < j`，这对很酷，当`a[i] + b[j] < 0`。 任务是准确地制作`k`这样的对。 这些值必须保持在`-n`和`n`。 

约束条件很大，有`n`最多`300000`，所以检查所有`O(n^2)`成对是不可能的。 最大尺寸时大约有`4.5 * 10^10`可能的配对，远远超出了两秒限制可以处理的范围。 我们需要一个运行时间最多大致为`O(n log n)`，并且理想情况下接近线性。 

没有不可能的价值`k`。 每个整数来自`0`通过`n(n-1)/2`可以通过下面的构造来实现，所以答案总是`Yes`。 原始问题正是使用这些边界和排序条件。 

第一个边缘情况是`n = 1`。 唯一可能的值是`k = 0`，因为没有配对`i < j`。 例如，```
1 0
1
1
```必须产生`Yes`， 不是`No`。 假设至少存在一对的解决方案可能会在这里意外失败。 

第二个边缘情况是`k = 0`。 例如，```
3 0
1 2 3
1 2 3
```需要每一双都是不酷的。 仅仅构建一个积极的解决方案是不够的`k`然后留下未初始化的边界值。 在目标达到零后，该结构故意停止创建冷对。 

第三个边缘情况是最大可能值，```
3 3
1 2 3
1 2 3
```三对中的每一对都必须很酷。 该结构通过使所有相关的`b`值等于零和全部`a`值为负。 一个粗心的实现使用`<= 0`除了所需的严格不平等之外，还可能做出错误的边界决策。 

第四种边缘情况是当目标严格落在一个位置的贡献范围内时。 例如，```
4 5
1 2 3 4
4 3 2 1
```必须中途停下来`q`位置。 只需分配每个`b`任何一个`0`或者`n`只能产生一定的总数。 部分赋值给了我们缺失值。 

## 方法

 直接的方法是尝试将值分配给`a`和`b`，然后计算每一对`(i,j)`和`i < j`和`a[i] + b[j] < 0`。 即使数组已经构造完毕，以这种方式检查答案也需要`O(n^2)`运营。 为了`n = 300000`，这大约是`4.5 * 10^10`配对检查，因此它不能成为公认算法的一部分。 

有用的观察是我们不需要搜索任意数组。 我们可以刻意地让价值观`a`一切都截然不同且消极。 放`a[p_t] = t - 1 - n`。 

于是，沿着`p`，这些值恰好是`-n, -n+1, ..., -1`，因此所需的排序是自动的。 

现在考虑一个固定索引`j`并假设`b[j] = 0`。 由于每`a[i]`都是负数，每个指标`i < j`与`j`。 它的贡献正是`j - 1`。 

在另一个极端，如果`b[j] = n`， 然后`a[i] + b[j] >= 0`对于每一个`i`， 因为`a[i] >= -n`。 它的贡献为零。 

这为我们提供了一种方便的方式来消耗目标`k`。 我们按照以下给出的顺序处理位置`q`。 对于当前职位`x = q_t`, 分配`b[x] = 0`准确贡献`x - 1`。 如果剩余目标至少为`x - 1`，我们获取所有这些对。 

最终有一个第一个位置，剩余的目标`r`小于`x - 1`。 那时我们正好需要`r`的`x - 1`可能的配对涉及`x`。 由于价值观`a[1], ..., a[x-1]`是不同的，对它们进行排序。 如果`c`是排序列表，设置`b[x] = -c[r]`从零开始的索引使得`r`这些值满足`a[i] + b[x] < 0`。 

在该位置之后，每个剩余的`b`可以是`n`，贡献为零。 

这些分配还保留了所需的顺序`b`。 在部分位置之前，值为`0`。 在部分位置，`b[x]`介于`1`和`n`。 之后的值为`n`。 于是沿着`q`序列是非递减的。 

这种构造与该问题的已发布解决方案中使用的中心思想相同：使一个数组严格排序，并使用另一个数组的单个部分分配位置来实现最终余数。

 | --- | --- | --- | --- |
 | 蛮力 |`O(n^2)`|`O(n)`| 太慢了|
 | 最佳|`O(n log n)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 创建`a`根据`p`通过设置`a[p[t]] = t - n - 1`对于基于一的`t`。 结果值为`-n, -n+1, ..., -1`， 所以`a`严格地沿着`p`并且每个值都在允许的范围内。 
2. 初始设置间隔`b[i] = n`。 这样的值不会产生很酷的配对，因为`a[i] + n >= 0`。 
3. 处理元素`q`从左到右。 设当前元素为`x = q[t]`。 如果我们设置`b[x] = 0`，那么每个索引`i < x`很酷`x`，准确给出`x - 1`新对。 
4. 如果剩余目标`k`至少是`x - 1`， 放`b[x] = 0`并减去`x - 1`从`k`。 这完全利用了该职位可用的贡献。 
5. 否则，剩余目标满足`0 <= k < x - 1`。 考虑价值观`a[1], ..., a[x-1]`并将它们逐渐排序为`c`。 放`b[x] = -c[k]`，使用从零开始的索引。 正是第一个`k`的值`c`严格小于`c[k]`，所以确切地说`k`指数`i < x`满足`a[i] + b[x] < 0`。 
6. 每隔一段时间就离开`b[q[t]]`等于`n`。 他们没有做出任何贡献，因此酷对的总数保持不变。 
7. 输出`Yes`， 其次是`a`和`b`。 此时目标必须已达到零，因为所有位置的总容量为`1 + 2 + ... + (n-1) = n(n-1)/2`，这是允许的最大值`k`。 

### 为什么它有效

 不变量是在处理了一些前缀之后`q`，已分配的位置贡献的量恰好等于已消耗的原始目标的量，而所有未处理的位置贡献量为零。 当整个贡献`x-1`拟合，将零分配给`b[x]`消耗了那么多对。 当它不适合时，不同的值`a[1..x-1]`让我们从中选择任意数字`0`通过`x-2`通过选择适当的阈值。 由于所有后来的值`b`是`n`，没有后来的一对可以变得很酷。 因此最终的酷对数量正是所要求的`k`。 

订购限制也来自于构造。 的价值观`a`严格沿着`p`。 的价值观`b`沿着`q`具有零的形式，可能是一个值`[1,n]`， 然后`n`s，所以它们是非减的。 每个分配的值都位于`[-n,n]`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    p = list(map(int, input().split()))
    q = list(map(int, input().split()))

    a = [0] * (n + 1)
    b = [n] * (n + 1)

    # Along p, a contains -n, -n+1, ..., -1.
    for pos, x in enumerate(p):
        a[x] = pos - n

    remaining = k

    for x in q:
        full = x - 1

        if full <= remaining:
            # b[x] = 0 makes every i < x cool.
            b[x] = 0
            remaining -= full
        else:
            # Need exactly 'remaining' cool pairs ending at x.
            # a[1..x-1] are all distinct.
            values = sorted(a[1:x])

            # values[remaining] is the (remaining + 1)-st
            # smallest value. Exactly 'remaining' values are smaller.
            b[x] = -values[remaining]

            remaining = 0
            break

    print("Yes")
    print(*a[1:])
    print(*b[1:])

if __name__ == "__main__":
    solve()
```第一个循环建立了固定结构`a`。 与零基础的`pos`，作业`pos - n`产生`-n`对于第一个元素`p`和`-1`对于最后一个。 

第二个循环实现贪婪过程。 变量`remaining`是仍需要的酷对数量。 什么时候`x - 1 <= remaining`， 环境`b[x]`为零是安全的，因为它使用所有以`x`。 

部分情况是唯一需要排序的地方。 切片`a[1:x]`恰好包含属于小于以下索引的值`x`。 因为所有的值`a`是不同的，`values[remaining]`正好有`remaining`较小的元素。 否定它给出了严格不平等的正确阈值。 

表达式`values[remaining]`而不是`values[remaining - 1]`是一个常见的误差点。 如果`remaining = 0`，我们不需要值`a[1:x]`为了满足不等式，所以我们选择最小值并使不等式足够严格以选择零个元素。 

作业`b[x] = -values[remaining]`总是在允许的范围内，因为每个`a`价值在于`[-n,-1]`，所以它的否定在于`[1,n]`。 

Python 整数具有任意精度，因此潜在的大值`n(n-1)/2`不溢出。 输入被读取`sys.stdin.readline`根据大的要求`n`。

## 边缘情况

 对于`n=1`，输入```
1 0
1
1
```创造`a[1] = -1`。 目前的`q`位置是`1`，其全部贡献为`0`， 所以`b[1]`变为零，剩余目标保持为零。 根本没有对，因此输出有效。 

为了`k=0`， 考虑```
3 0
1 2 3
1 2 3
```第一个位置有`x=1`，所以它的全部贡献为零。 在`x=2`，所需的目标已经为零，并且`x-1=1`，因此算法进入部分情况。 唯一较早的值是`a[1]=-3`，并且它分配`b[2]=3`。 自从`a[1]+3=0`，严格的不等式失败，给出零个酷对。 其余`b`值是`3`，也产生零对。 该建筑精确地处理了严格的边界。 

对于最大目标，```
3 3
1 2 3
1 2 3
```的价值观`a`是`[-3,-2,-1]`。 职位在`q`贡献`0`,`1`， 和`2`分别，所有三个都完全通过分配`b`等于零。 每对都有一个负数`a`值加零，所以三对都很酷。 

对于部分贡献，请考虑```
4 5
1 2 3 4
4 3 2 1
```第一个`q`值为`4`，贡献三对并离开`2`。 接下来是`3`，再贡献两个，剩下零。 下一个位置无法做出任何贡献，因为目标已经为零，因此部分构造选择最小的前一个位置`a`值作为其阈值。 这给出了零个额外的对，并且剩余的位置接收`n`。 最终的计数正好是`5`。 

结构永远不需要打印的原因`No`是允许区间内的每个目标都可以贪婪地分解为全部贡献`q_t-1`加上最后的余数。 所有这些容量的总和是`(q_1-1) + (q_2-1) + ... + (q_n-1) = n(n-1)/2`。 

最后的部分位置可以实现低于其容量的每个余数，因为前面的`a`价值观是不同的。 该组合涵盖了整个所需范围`k`。
