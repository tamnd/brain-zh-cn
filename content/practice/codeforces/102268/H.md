 ## 解决方案
 ## 问题理解

 我们需要构造一个每边都有 n 个顶点的二分图。 对于左顶点的子集 A，其邻域 N(A) 由 A 的至少一个顶点所触及的每个右顶点组成。当子集需要比实际可用的更多不同的右顶点时，该子集是关键的，这意味着 ∣N(A)∣<∣A∣。 

输入给出n（n≤20）和目标数k（0≤k<2n）。 左侧有 2 n 个子集，包括空子集。 空子集从来都不是关键的，因为它的大小和邻域大小都为零。 我们的图必须使剩余 2 n −1 个子集中的 k 个成为关键。 

小值 n≤20 强烈暗示子集枚举可以用于验证，但不足以在图上自由搜索。 n+n 个顶点上的二分图有 n 2 个可能的边，因此枚举图需要 2 n 2 个可能性，当 n=20 时，这已经是 2 400 种。 我们需要一个直接构造，其描述只有多项式大小。 

有两种边界情况特别容易处理不当。 对于 n=1,k=0，图必须包含单边。 唯一的非空子集有一个邻居并且不是关键的。 不输出任何边的粗心构造反而会使唯一的子集变得关键。 对于 n=1,k=1，正确的图没有边，因为单例左子集有零个邻居并且是关键的。 另一个常见错误是将空子集视为关键子集。 它从来都不是，所以非关键非空子集的数量是 2 n −1−k，而不是 2 n −k。 

## 方法

 直接的强力解决方案可以采用候选图并枚举左侧的每个子集。 对于每个子集，我们可以扫描它的顶点并收集它们的右侧邻居，然后比较两个基数。 如果图由 n×n 邻接矩阵表示，则需要 O(n 2 2 n ) 运算。 当 n=20 时，大约为 400⋅1,048,576，或者大约 4.2×10 8 次基本检查。 通过枚举所有可能的边集来搜索图本身会更糟糕，因为有 2 n 2 个可能的图。 

有用的观察是我们不需要任意图。 我们可以故意构建一个非常有限的族，其关键子集很容易计算。 

设左侧顶点为 1,…,n，并选择整数

 n≥a 1 ​ ≥a 2 ​ ≥⋯≥a n ​ ≥0。 

将左顶点 i 恰好连接到第一个 a i 右顶点。 考虑一个非空子集 A，并令 i 为其最小左顶点。 由于序列 a i ​是非增的，因此每个其他选定的顶点 t>i 都有 t ​ ≤a i ​。 因此它们所有邻域的并集正是第一个 a i 右顶点，所以

 ∣N(A)∣=a i ​ .

 i 之后有 n−i 个顶点。 如果恰好选择了其中 j 个，则子集的大小为 j+1，并且准确地何时出现并不重要

 j+1≤a i ​ ,

 或 j≤a i −1。 因此，最小顶点为 i 的非关键子集的数量为

 j=0 Σ a i ​ −1 ​ ( j n−i ​ )。 

对所有可能的最小顶点求和给出

 G= i=1 Σ n ​ j=0 Σ a i ​ −1 ​ ( j n−i ​ ),

 其中 G 是非关键非空子集的数量。 由于有 2 n −1 个非空子集，我们需要

 G=2n-1-k。 

剩下的问题是如何选择a i​。 内部和是帕斯卡三角形的一行的前缀。 处理从 n−1 到 0 的行。在第 r 行中，贪婪地取

 ( 0 r ),( 1 r ),( 2 r ),…

 只要当前的余数足够大。 取前 t 项与设置相应的 a i ​ =t 完全相同，因为这有助于

 j=0 Σ t−1 ​ ( j r ​ )。 

停止后，余数小于下一个二项式系数。 特别地，它至多为 2 r -1，这正是 r 元素的非空子集的最大数量。 然后可以将相同的参数递归地应用于其余行。

这给出了直接的 O(n 2 ) 构造。 关键结构是帕斯卡三角形提供了足够的重叠的 2 次幂来表示 0 到 2 n −1 之间的每个可能目标。

 ## 算法演练

 1. 计算所需的非关键非空子集数量：

 G=2n-1-k。 

我们使用非关键子集，因为构造会自然地对它们进行计数。 空子集被 2 n -1 项排除。 
2. 构建帕斯卡三角形直至第 n−1 行，存储

 C[r][j]=( j r ​ ).

 由于n≤20，普通Python整数就绰绰有余了，最大值也只有( 9 19 ​ )。 
3. 从最后一个 Pascal 行开始，r=n−1，并将其与左顶点 1 关联。扫描 j=0,1,…,r。 每当当前余数 G 至少为 C[r][j] 时，减去该值并添加从左顶点 1 到右顶点 j+1 的边。 

如果我们选择 j=0,…,t−1，左顶点 1 的邻域恰好有 t 个顶点。 它对好子集数量的贡献正是前缀和

 j=0 Σ t−1 ​ ( j r ​ )。 
4. 一旦下一个二项式系数太大，就停止处理该行并移至 r−1。 下一行对应于左顶点 2，并且继续相同的过程。 

这个贪心步骤之所以安全，是因为在取最长的可能前缀之后，剩余的值小于第一个未使用的二项式系数。 因此它肯定小于 2 r，因此可以使用较小的 Pascal 行来表示。 
5. 继续直到第 0 行。每个选定的边的形式为 (i,j)，其中 1≤i,j≤n。 对于固定的左顶点，所选的右端点始终为 1,2,…,a i ​，因此不存在重复的边。 
6. 输出所有选定的边。 构造的图恰好有 G 个非关键非空子集，因此剩余的

 (2 n −1)−G=k

 子集至关重要。 

为什么它有效可以用一个不变量来概括。 处理完行 n−1,n−2,…,r+1 后，已选择的边恰好贡献从 G 中减去的量，并且剩余目标可以使用行 r,r−1,…,0 来表示。 当处理 r 行时，我们采用最长可能的二项式前缀。 如果不能采用下一项，则余数小于该项，因此小于 2 r，即剩余 r 行可表示的整个值范围。 不变量一直存在，直到余数变为零。 然后，邻域参数将每个选定的前缀长度转换为所需数量的非关键子集。 

## Python 解决方案```python
Pythonimport sysinput = sys.stdin.readline

def solve():    n, k = map(int, input().split())
    # Number of noncritical nonempty subsets we want.    need = (1 << n) - 1 - k
    # Pascal's triangle.    C = [[0] * (n + 1) for _ in range(n + 1)]    C[0][0] = 1    for i in range(1, n):        C[i][0] = C[i][i] = 1        for j in range(1, i):            C[i][j] = C[i - 1][j - 1] + C[i - 1][j]
    edges = []
    # Row r corresponds to left vertex n-r.    for r in range(n - 1, -1, -1):        left = n - r
        for j in range(r + 1):            if need >= C[r][j]:                need -= C[r][j]                edges.append((left, j + 1))            else:                break
    print(len(edges))    for u, v in edges:        print(u, v)
```变量`need`是仍需实现的非关键非空子集的数量。 最初它是 2 n −1−k，因为每个非空子集要么是关键的，要么是非关键的。 

帕斯卡三角形仅通过第 n−1 行构造。 递推直接计算贪心分解所需的二项式系数。 Python 中不存在溢出问题，即使在固定宽度语言中，此处的值对于 64 位整数来说也足够小。 

外循环处理`r`从`n - 1`降至零。 对应的左顶点是`n - r`，因此行 n−1 生成顶点 1 的邻域，行 n−2 生成顶点 2 的邻域，依此类推。 

在行内，边按其右端点的升序添加。 因此，如果一行接收 t 条边，它们恰好位于右侧顶点 1,...,t。 这就是给出计数参数所需的前缀邻域结构的原因。 

这`break`也具有重要意义。 一次`need < C[r][j]`，对于任意二项式行，该行中的每个后续项不一定都较大，因此粗心的实现不应简单地假设所有后续系数均不可用。 这里的构造特别需要采用前缀，因此我们在第一个不可用的术语处停止。 数学论证保证余数可以由较小的行处理。 

对于 n=20，输出最多包含 1+2+⋯+n=210 条边，因此构造完全在限制范围内。

 ## 边缘情况

 对于`1 0`，所需的非关键非空子集数量为

 2 1 −1−0=1。 

唯一的帕斯卡系数是( 0 0 ​ )=1，所以算法添加了边(1,1)。 单例左子集有一个邻居并且不是关键的，恰好给出零个关键子集。 

为了`1 1`，所需的非关键非空子集数量为零。 贪心循环不能减去任何东西，因此它不输出边。 唯一的非空子集的邻域大小为零，子集大小为一，因此至关重要。 答案恰好包含一个关键子集。 

为了`4 0`，非关键子集的目标数量为 15。该算法消耗第 3,2,1,0 行中的每个系数，将四个左侧顶点中的每个顶点的所有四个右侧顶点作为邻居。 任何非空子集的邻域大小为四，而其大小最多为四，因此没有子集是关键的。 

对于`4 15)，非关键子集的目标数量为零。 根本没有选择任何边。 每个非空子集都有一个空邻域，因此 2 4 -1=15 个非空子集中的每一个都是关键的。 

为了`20,2^{20}-1`，该算法再次需要零个非关键子集并输出空图。 每个非空左子集的邻域大小为零，因此所有 1,048,575 个非空子集都是关键的。 这也证实了该构造无需任何特殊情况算术即可处理 k 的上限。
