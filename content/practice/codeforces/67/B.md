 ## 解决方案
 ## 问题理解

 我们给出了一个排列`A`的数字来自`1`到`n`。 对于每个值`i`，我们知道一个数字`b[i]`。 这个数字描述了之前出现了多少个元素`i`在排列中并且至少是`i + k`。 

条件附加到值本身，而不是位置。 如果`i = 3`和`k = 2`，然后我们计算有多少个数字大于或等于`5`出现在之前`3`。 

任务是重建满足所有这些计数的字典顺序最小排列。 

约束条件`n ≤ 1000`对于二次算法来说足够小。 一个`O(n^2)`解决方案执行大约一百万次操作，这在时间限制内是微不足道的。 在最坏的情况下，Cubic 解决方案开始接近 10 亿次操作，并且在 Python 中是不安全的。 

棘手的部分是`b[i]`不描述通常意义上的反转。 每个值至少只关心数字`k`比它本身还大。 这意味着附近值之间的关系是不相关的。 

一个常见的错误是认为贪婪地在每个位置放置尽可能小的未使用数字总是有效的。 考虑：```
n = 4, k = 2
B = [0, 1, 0, 0]
```价值`2`至少需要一个较早的数字`4`。 唯一的候选人是`4`， 所以`4`必须出现在之前`2`。 如果我们贪婪地将小数字放在前面，我们可能会构建：```
1 2 3 4
```这违反了要求`2`。 

另一个微妙的情况出现时`k`很大。```
n = 5, k = 5
B = [0, 0, 0, 0, 0]
```没有值至少可以有更早的数字`i + 5`，因为这样的数字不存在。 每个排列都满足条件，因此字典顺序上最小的答案是：```
1 2 3 4 5
```粗心的实现可能仍然会尝试强制执行实际上不可能的依赖关系。 

一种更危险的边缘情况是多个值具有相同的要求。```
n = 5, k = 2
B = [0, 0, 0, 0, 0]
```这里每个小数都需要零个大的前辈。 字典顺序上最小的有效排列只是递增顺序。 如果我们以错误的方向处理值，我们可能会产生一个有效但非最小的答案，例如：```
3 1 4 2 5
```问题不仅仅是重建任何排列，而是按照字典顺序重建最小的排列。 

## 方法

 蛮力的想法很简单。 生成所有排列，计算对应的数组`B`，并返回与输入匹配的第一个排列。 计算`B`对于一个排列需要`O(n^2)`因为对于每个值，我们都可以扫描其左侧的所有内容。 真正的问题是排列的数量。 即使是为了`n = 10`， 有`10! ≈ 3.6 million`的可能性。 在`n = 1000`，穷举搜索是完全不可能的。 

为了改善这一点，我们需要了解计数的实际含义。 

假设我们看一个值`i`。 仅来自以下号码`i + k`到`n`重要的是它的计数。 较小的值无关紧要。 让：```
big(i) = count of numbers >= i + k
```确切地说有：```
n - (i + k) + 1 = n - i - k + 1
```这样的数字，当`i + k ≤ n`。 

价值`b[i]`告诉我们这些大数字中有多少出现在之前`i`。 剩余的大数必须出现在`i`。 

这开始看起来像是元素之间的排序约束。 

一个更有用的观点是从最大值向下构建排列。 

当我们处理价值时`i`，所有值至少`i + k`是已知的。 它们的相对位置是固定的。 我们只需要决定插入到哪里`i`其中，正是这样`b[i]`这些大值的一部分保留在它之前。 

假设有`m`已经放置的大值。 如果确切地说`b[i]`其中必须在之前`i`， 然后`i`必须紧接在第一个之后插入`b[i]`大值。 

值介于`i + 1`和`i + k - 1`根本不影响计数，因此它们的位置与此条件无关。 

这给出了一个干净的贪婪结构。 

我们处理来自`n`下降到`1`。 对于每个值`i`，我们将其插入当前序列中精心选择的位置。 由于我们稍后插入较小的值，因此在序列中较早放置较小的值会尽可能改善字典顺序。 

最终复杂度变为`O(n^2)`，很容易满足约束条件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!·n²) | O(n!·n²) | O(n) | 太慢了|
 | 最佳 | O(n²) | O(n) | 已接受 |

 ## 算法演练

 1. 从空序列开始。 
2. 过程值来自`n`下降到`1`。 
3. 对于当前值`i`，识别所有已插入的值，这些值至少是`i + k`。 

这些正是有助于的价值观`b[i]`。 
4. 从左到右扫描当前序列并计算看到了多少个贡献值。 
5. 插入`i`在第一个位置`b[i]`贡献价值仍然摆在面前。 

如果`b[i] = 0`，我们放置`i`尽早。 

如果`b[i] = 2`，我们在插入之前跳过两个贡献值。 
6. 继续，直到插入所有值。 
7. 输出最终序列。 

### 为什么它有效

 加工时`i`，每个值至少`i + k`已经被放置了，因为我们从较大的数字处理到较小的数字。 较小的值永远不会影响`b[i]`，因此未来的插入是无害的。 

插入位置保证准确`b[i]`有效贡献者之前停留`i`。 因为我们总是插入`i`尽可能早地保留此计数，由此产生的排列在字典顺序上是最小的。 

关键的不变量是：```
After processing values from n down to i,
all conditions for processed values are already permanently satisfied.
```未来的插入仅涉及较小的数字，这不会对任何处理值的计数产生影响。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    b = list(map(int, input().split()))

    perm = []

    for i in range(n, 0, -1):
        need = b[i - 1]

        cnt = 0
        pos = len(perm)

        for j in range(len(perm) + 1):
            if cnt == need:
                pos = j
                break

            if j < len(perm) and perm[j] >= i + k:
                cnt += 1

        perm.insert(pos, i)

    print(*perm)

solve()
```数组`perm`存储部分构造的排列。 

我们按降序处理值，因为每个值都会影响`i`在我们决定放置位置之前必须已经在场`i`。 

内循环搜索最早的插入点，准确产生`b[i]`大前辈。 该循环内的操作顺序很重要。 我们首先检查当前合格前辈的数量是否等于所需的数量。 只有在那之后我们才能超越另一个元素。 

这可以避免差一错误。 认为`need = 0`。 我们必须在第一个限定元素之前插入，而不是在其之后。 

条件：```
perm[j] >= i + k
```直接实现定义。 只有足够大的值才会起作用。 

Python列表插入是`O(n)`，但与`n ≤ 1000`，总复杂度仍然是二次的。

 ## 边缘情况

 考虑：```
4 2
0 1 0 0
```价值`2`至少需要一个较早的值`4`。 该算法处理：```
4 -> [4]
3 -> [3, 4]
2 -> [3, 4, 2]
1 -> [1, 3, 4, 2]
```仅有的`4`有助于`2`，并且它出现在之前`2`，所以条件满足。 将小数字放在首位的天真贪婪方法将会失败。 

现在考虑：```
5 5
0 0 0 0 0
```对于每个值`i`，阈值`i + 5`超过`n`。 不存在贡献者。 在插入过程中，算法立即发现`cnt == need == 0`并在开头插入每个值：```
[5]
[4,5]
[3,4,5]
[2,3,4,5]
[1,2,3,4,5]
```最终的排列在字典顺序上是最小的。 

最后，考虑：```
5 2
0 0 0 0 0
```每个值都需要零个大的前辈。 该算法始终将每个值插入到第一个合格的大元素之前。 这会尽可能地将较小的数字推向前面，从而产生：```
1 2 3 4 5
```而不是另一个有效但字典顺序更大的排列。
