 ## 解决方案
 ## 问题理解

 我们有一排学生，对于每一对相邻的学生，我们只知道他们分数的相对顺序。 如果位置之间的关系特征`i`和`i + 1`是：

-`L`，然后是学生`i`收到的太妃糖必须严格多于学生`i + 1`-`R`，然后是学生`i + 1`收到的太妃糖必须严格多于学生`i`-`=`，那么两个学生必须收到相同数量的太妃糖

 每个学生必须至少收到一颗太妃糖，并且在满足关系的所有作业中，我们想要总金额最小的那一个。 

输入的不是实际的标记。 相反，它直接给出了相邻学生之间的约束。 如果关系字符串有长度`n - 1`，然后是字符`s[i]`描述位置之间的关系`i`和`i + 1`。 

约束条件`n ≤ 1000`相当小。 甚至一个`O(n^2)`解决方案会很顺利地通过，因为最坏的情况是大约一百万次操作。 这意味着我们不需要复杂的数据结构或经过大量优化的图形算法。 挑战在于推理局部不平等如何在全球范围内相互作用。 

棘手的部分是，改变一个位置可能会迫使邻居重复更新。 过早做出的天真贪婪的选择可能会在以后打破限制。 

考虑这个例子：```
4
RRR
```限制条件是：```
a1 < a2 < a3 < a4
```最小有效分配是：```
1 2 3 4
```一个粗心的从左到右的贪婪算法总是给出当前最小的有效值，可能会分配：```
1 2 1 2
```第三个关系失败是因为`a2 < a3`不再是真的。 

另一个危险的情况是长链递减：```
5
LLLL
```约束变为：```
a1 > a2 > a3 > a4 > a5
```正确的最小分配是：```
5 4 3 2 1
```如果我们将所有内容初始化为`1`并且仅修复局部违规一次，我们可能会在效果一直向左传播之前停止得太早。 

平等也很重要，因为它们将职位连接到必须共享相同价值观的组中。 

例子：```
5
R==L
```关系是：```
a1 < a2 = a3 = a4 > a5
```最小分配是：```
1 2 2 2 1
```如果相等被视为“无限制”而不是“相同的值”，我们可能会错误地生成：```
1 2 1 2 1
```这违反了`a2 = a3`。 

## 方法

 一个简单的蛮力想法是让每个学生从一颗太妃糖开始，然后反复扫描关系。 每当违反约束时，就增加一侧，直到关系变得有效。 

例如，如果我们看到`R`在位置`i`目前`a[i] >= a[i+1]`，我们增加`a[i+1]`到`a[i] + 1`。 同样，对于`L`，我们在需要时增加左侧。 为了`=`，我们同步两个值。 

这个过程最终会收敛，因为值只会增加，并且每次更新都会修复至少一个违规行为。 最终的分配是最小的，因为我们只在被迫时提高值。 

问题是更新可以在阵列中重复传播。 在最坏的情况下，每次扫描仅修复一个位置，导致大约`O(n^2)`运营。 

关键的观察是每个关系仅取决于相邻位置。 不断增加的需求朝一个方向流动。 

对于像这样的链：```
RRRR
```每个位置取决于左邻居。 最小值可以从左到右构建。 

为了：```
LLLL
```依赖关系从右到左流动。 

这表明将问题分为两个方向。 

我们维护一个用 1 初始化的数组。 

在从左到右的传递过程中，我们处理所有`R`关系。 如果位置`i + 1`必须大于位置`i`，那么最小的有效选择是：```
a[i+1] = a[i] + 1
```在从右到左传递期间，我们处理所有`L`关系。 如果位置`i`必须超过位置`i + 1`，那么最小的有效选择是：```
a[i] = max(a[i], a[i+1] + 1)
```可以通过在两次传递期间适当地复制值来处理相等性。 

重要的见解是，每个约束只会将值推高到所需的最小量。 一旦处理了两个方向依赖性，所有不等式同时成立。

 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 已接受 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 创建数组`a`长度`n`并将每个值初始化为`1`。 

每个学生必须至少收到一颗太妃糖，所以`1`是可能的最小起点。 
2. 从左向右遍历。 

对于位置上的每个关系`i`：

- 如果`s[i] == 'R'`，然后是学生`i + 1`必须收到比学生更多的钱`i`。 
- 放：```
a[i+1] = a[i] + 1
```- 如果`s[i] == '='`，那么两个学生必须具有相同的值。 
- 放：```
a[i+1] = a[i]
```此遍解决了依赖关系从左向右移动的所有约束。 
3. 从右向左遍历。 

对于位置上的每个关系`i`：

- 如果`s[i] == 'L'`，然后是学生`i`必须收到比学生更多的钱`i + 1`。 
- 放：```
a[i] = max(a[i], a[i+1] + 1)
```- 如果`s[i] == '='`，那么两个学生必须再次匹配。 
- 放：```
a[i] = max(a[i], a[i+1])
a[i+1] = a[i]
```这`max`是必要的，因为由于早期的约束，从左到右的传递可能已经分配了更大的值。 
4. 打印结果数组。 

### 为什么它有效

 从左到右的传递计算满足表单的每个递增依赖性所需的最小值`a[i] < a[i+1]`。 从右到左的传递计算形式的每个递减依赖项所需的最小值`a[i] > a[i+1]`。 

任何步骤都不会不必要地增加价值。 每次更新都会将位置设置为能够满足本地约束的最小数量，同时保留先前建立的要求。 

两次通过后，每个相邻关系都得到满足。 由于所有值都从最小可能值开始`1`并且仅在受到约束时才增加，总和很小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    a = [1] * n

    for i in range(n - 1):
        if s[i] == 'R':
            a[i + 1] = a[i] + 1
        elif s[i] == '=':
            a[i + 1] = a[i]

    for i in range(n - 2, -1, -1):
        if s[i] == 'L':
            a[i] = max(a[i], a[i + 1] + 1)
        elif s[i] == '=':
            val = max(a[i], a[i + 1])
            a[i] = val
            a[i + 1] = val

    print(*a)

solve()
```解决方案首先为每个学生分配一颗太妃糖。 这保证了最低的合法基础状态。 

第一遍处理向右流动的依赖关系。 当我们看到`R`，右边的学生必须严格大于左边的学生，因此我们分配的值恰好比左边的学生多 1。 当我们看到`=`，我们复制相同的值，因为相等性必须完全成立。 

第二遍处理左向依赖性。 为了`L`，左边的学生必须比右边的学生至少多一。 我们使用`max`因为根据之前的约束，左侧可能已经足够大了。 

向后传递中的相等处理很微妙。 假设一侧由于另一条链条而变大。 平等意味着双方必须分享更大的价值。 如果我们只更新一个方向，平等可能会被打破。 

循环：```
for i in range(n - 2, -1, -1):
```也容易出错。 我们从`n - 2`因为关系`s[i]`连接位置`i`和`i + 1`。 

不存在整数溢出问题，因为`n ≤ 1000`，所以最大可能值至多是`1000`。

 ## 边缘情况

 长递减链是打破单向解决方案的最简单方法。 

输入：```
5
LLLL
```从左到右遍历之后，数组仍然是：```
1 1 1 1 1
```向后传递从末尾开始处理约束：```
a[3] = 2
a[2] = 3
a[1] = 4
a[0] = 5
```最终结果：```
5 4 3 2 1
```这说明了为什么从右到左传播是必要的。 每次更新都取决于其右侧已经正确的值。 

平等链要求两次传递同步。 

输入：```
4
===
```第一遍复制整个链上的值：```
1 1 1 1
```第二遍使它们保持同步。 由于没有不平等强制增加，所以最小有效分配仍然是全1。 

混合的平等和不平等关系可以产生微妙的传播效应。 

输入：```
5
R==L
```前向传播构建：```
1 2 2 2 1
```向后传递检查最终结果`L`关系并证实`2 > 1`已经成立。 相等同步保留中间块。 

仅在一个方向复制等式的有缺陷的实现可能会意外地产生：```
1 2 2 1 1
```这违反了`a3 = a4`。 

交替约束测试算法是否避免不必要的增加。 

输入：```
6
LRLRL
```最小有效分配是：```
2 1 2 1 2 1
```该算法永远不会将值夸大到超出每个局部关系所需的值。 这种极简性正是从 1 开始并且只有在强制正确工作时才会增加的原因。
