 ## 解决方案
 ## 问题理解

 我们得到一个十进制整数作为字符串。 该数字可能非常大，长达 100 位，因此它可能不适合许多编程语言中的普通整数类型。 

任务是确定可以存储该值的最小 Java 整数类型。 按以下顺序检查可用类型：`byte`,`short`,`int`,`long`，最后`BigInteger`。 每个原始类型都有一个固定的包含范围。 我们必须打印范围包含给定数字的第一个类型。 

主要困难来自输入大小。 100 位整数远大于 64 位有符号整数，因此在具有固定宽度整数的语言中直接将输入转换为普通数字类型是危险的。 粗心的实现可能会在比较发生之前就溢出。 

就输入大小而言，限制很小。 我们只处理一个长度最多为 100 的字符串，因此即使是线性时间的工作也是微不足道的。 问题不在于优化，而在于安全比较和正确处理边界值。 

一些边缘情况可能会悄悄地破坏不正确的解决方案。 

考虑输入：```
128
```正确答案是：```
short
```

`byte`结束于`127`，并且边界是包容性的。 严格的`<`比较而不是`<=`会拒绝`127`错误或接受`128`错误地。 

另一个危险的情况是：```
9223372036854775808
```正确答案是：```
BigInteger
```该值恰好比最大有符号 64 位整数大 1。 在 C++ 或 Java 中，尝试将其直接解析为`long long`或者`long`会溢出。 更安全的方法是任意精度算术或直接字符串比较。 

一个较小但微妙的例子是：```
2147483647
```正确答案是：```
int
```这是确切的上限`int`，因此算法必须将限制视为包含在内。 

## 方法

 暴力方法会尝试将数字解析为越来越大的数字类型并捕获失败。 在 Python 中，这是可行的，因为 Python 整数是任意精度的，但在具有固定宽度整数的语言中，这会变得有风险。 在我们比较之前，将 100 位数字解析为普通整数类型可能会溢出。 

另一种暴力式解决方案是将输入字符串与每个范围中的每个可能的整数进行比较，但这显然是不可行的。 甚至连`long`范围包含超过$10^{18}$价值观。 

有用的观察是我们只需要将输入与四个固定边界值进行比较：

 - 127
 - 32767
 - 2147483647
 - 9223372036854775807

 如果该数字小于或等于这些限制之一，则该类型可以存储它。 

因为Python自然支持任意精度整数，所以最简单的接受解决方案是将字符串转换为整数一次，然后按顺序与已知限制进行比较。 输入长度只有 100 位，因此解析成本较低。 

该算法变成了从最小类型向上的比较序列。 第一个匹配范围立即给出答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 重复解析/不安全的定宽转换 | O(L) | O(1) | O(1) | 许多语言都有风险|
 | 与限制的顺序比较| O(L) | O(1) | O(1) | 已接受 |

 这里，$L$是输入中的位数。 

## 算法演练

 1. 以字符串形式读取输入数字。 
2. 将字符串转换为Python整数。 

Python 整数具有任意精度，因此即使是 100 位数字的值也可以安全处理。 
3. 将值与`byte`上限`127`。 

如果该值最多为`127`， 打印`"byte"`并停止。 
4. 否则与`short`上限`32767`。 

如果该值适合此处，则打印`"short"`。 
5. 否则与`int`上限`2147483647`。 

如果该值适合此处，则打印`"int"`。 
6. 否则与`long`上限`9223372036854775807`。 

如果该值适合此处，则打印`"long"`。 
7. 如果前面的范围都不起作用，则打印`"BigInteger"`。 

### 为什么它有效

 整数类型按容量递增排序。 如果里面有一个数字`byte`，这自动是最小的有效类型，因为每个早期的类型都较小。 同样的逻辑适用于`short`,`int`， 和`long`。 

该算法完全按照这个顺序检查限制。 第一次成功的比较确定了最小的有效类型，因此答案始终是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())

if n <= 127:
    print("byte")
elif n <= 32767:
    print("short")
elif n <= 2147483647:
    print("int")
elif n <= 9223372036854775807:
    print("long")
else:
    print("BigInteger")
```该程序首先读取输入并将其转换为 Python 整数。 这是安全的，因为 Python 整数不会因大值而溢出。 

比较按从最小类型到最大原始类型的顺序进行。 这个顺序很重要。 如果我们检查`long`首先，然后每个较小的值也会匹配`long`，并且我们将失去返回最小拟合类型的要求。 

比较使用`<=`因为范围是包含在内的。 价值观如`127`和`2147483647`仍必须属于`byte`和`int`分别。 

决赛`else`处理大于最大有符号 64 位整数的每个数字。 这些值需要`BigInteger`。

 ## 边缘情况

 考虑输入：```
127
```该算法检查：```
127 <= 127
```这是真的，所以它打印：```
byte
```这证实了边界是包容性的。 使用严格的`<`比较会错误地拒绝该值。 

现在考虑：```
128
```第一次比较失败：```
128 <= 127
```接下来比较成功：```
128 <= 32767
```所以输出变成：```
short
```这验证了相邻整数类型之间的转换。 

更危险的情况是：```
9223372036854775808
```比较继续进行，直到`long`查看：```
9223372036854775808 <= 9223372036854775807
```这是错误的，因此算法进入最后一个分支并打印：```
BigInteger
```这种情况捕获了依赖于固定宽度整数解析的实现，并在比较之前意外溢出。
