 ## 解决方案
 ## 问题理解

 对于固定指数`k`， 定义`sigma_k(i)`作为总和`k`所有约数的 -th 次幂`i`。 该任务不是要求该函数的一个值，而是要求两个大前缀和的异或。 对于每个测试用例，我们给出两个小指数`a`和`b`，和一个极限`n`。 我们需要计算总和`sigma_a(i)`对于每一个`i`从`1`到`n`，做同样的事情`sigma_b(i)`，将两个结果异或，仅保留最低 64 位。 

指数被限制为`0, 1, 2, 3`， 但`n`可以达到`10^12`。 对所有数字的直接模拟`n`在最坏的情况下需要迭代一万亿次，这远远超出了 2 秒的限制。 甚至一个`O(n log n)`除数枚举方法大致需要`10^13`运算，因此解决方案必须利用除数和的数学结构。 

主要的边缘情况来自于大小`n`以及所需的 64 位行为。 例如，当`n=1`,`a=0`， 和`b=1`，唯一考虑的数字是`1`。 两个除数之和均为`1`，所以异或是`0`。```
Input:
1
0 1 1

Output:
0
```一个从以下位置开始循环的解决方案`d=0`会失败，因为除数开始于`1`。 

另一个容易犯的错误是忘记答案是模数`2^64`。 例如，对于大的除数和的前缀和可能会超出正常有符号 64 位整数的范围`n`，因此使用具有任意精度的语言实现需要显式应用掩码。 

为了`n=4`,`a=0`， 和`b=1`，两个前缀和为：```
sigma_0: 1, 2, 2, 3 -> total 8
sigma_1: 1, 3, 4, 7 -> total 15
```正确答案是：```
8 XOR 15 = 7
```一个粗心的实现将异或与加法混淆，会输出`23`。 

## 方法

 一种直接的方法是直接遵循定义。 对于每个整数`i`从`1`到`n`，我们可以枚举它的除数，计算`sigma_a(i)`和`sigma_b(i)`，然后添加它们。 这是正确的，因为它从字面上评估了数学定义。 

问题在于规模。 最大的测试用例包含`n=10^12`，所以即使触及每个值`i`是不可能的。 基于除数的枚举甚至会更慢，因为每个数字都必须进行因式分解或扫描除数。 

关键的观察是求和的顺序可以交换。 不要询问每个数字属于哪些除数，而是询问有多少个数字包含特定除数。 除数`d`贡献`d^k`到每一个倍数`d`，并且正好有`floor(n/d)`这样的倍数。 所以：$$\sum_{i=1}^{n}\sigma_k(i)=\sum_{d=1}^{n} d^k\left\lfloor\frac nd\right\rfloor$$剩下的挑战是总和似乎仍然有`n`条款。 重要的属性是`floor(n/d)`在长距离内保持恒定。 如果`floor(n/l)=q`，那么每一个`d`在某个时间间隔结束于`r=floor(n/q)`有相同的商`q`。 

这让我们可以处理范围而不是单个除数。 大约只有`2*sqrt(n)`这样的范围，大约是 200 万`n=10^12`。 对于每个范围，我们需要总和`d^k`两个边界之间。 自从`k`至多是`3`，封闭形式的前缀公式就足够了。 

暴力破解之所以有效，是因为它正确地计算了每个除数的贡献，但它却失败了，因为它执行了太多的小操作。 商分组观察将许多相同的项压缩到一个计算中。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n) 或更糟 | O(1) | O(1) | 太慢了 |
 | 商分组| O(sqrt(n)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个需要的指数`k`，计算值$$F_k(n)=\sum_{d=1}^{n}d^k\left\lfloor\frac nd\right\rfloor$$使用商范围而不是迭代每个除数。 

1. 起始范围为`l=1`。 商是`q=n//l`。 最后一个商保持不变的位置是`r=n//q`。 

整个区间`[l,r]`贡献：$$q \times \sum_{d=l}^{r}d^k$$因为这个区间中的每个除数都有相同的乘数。 

1. 根据前缀公式求出区间的幂和。 所需的公式是：$$\sum d = \frac{x(x+1)}2$$

$$\sum d^2=\frac{x(x+1)(2x+1)}6$$

$$\sum d^3=\left(\frac{x(x+1)}2\right)^2$$这`k=0`case 只是区间内数字的计数。 

1. 将贡献值与答案模数相加`2^64`，然后继续从`r+1`。 
2. 计算两个所需的前缀和，对它们进行异或，然后输出结果 64 位值。 

正确性来自除数贡献变换。 每对`(i,d)`在哪里`d`划分`i`在原始定义中只计算一次。 交换顺序后，处理除数时算同一对`d`，乘以有效倍数的数量。 商分组仅将相邻的除数与相同的乘数组合在一起，因此它改变了计算顺序，但不会改变值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1 << 64

def prefix_power(x, k):
    if k == 0:
        return x & (MOD - 1)
    if k == 1:
        return (x * (x + 1) // 2) & (MOD - 1)
    if k == 2:
        return (x * (x + 1) * (2 * x + 1) // 6) & (MOD - 1)
    t = x * (x + 1) // 2
    return (t * t) & (MOD - 1)

def calc(n, k):
    ans = 0
    l = 1

    while l <= n:
        q = n // l
        r = n // q

        segment = (prefix_power(r, k) - prefix_power(l - 1, k)) & (MOD - 1)
        ans = (ans + q * segment) & (MOD - 1)

        l = r + 1

    return ans

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return

    t = int(data[0])
    idx = 1
    cache = {}
    out = []

    for _ in range(t):
        a = int(data[idx])
        b = int(data[idx + 1])
        n = int(data[idx + 2])
        idx += 3

        if n not in cache:
            cache[n] = [calc(n, k) for k in range(4)]

        out.append(str((cache[n][a] ^ cache[n][b]) & (MOD - 1)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```这`prefix_power`函数实现了算法所需的四种封闭形式。 除法发生在求模运算之前，因为公式包含分数，过早应用求模会破坏整数结果。 

这`calc`函数执行商分组。 变量`l`和`r`描述当前除数区间。 直接移动到`r+1`避免单独处理每个除数。 

缓存存储给定的所有四个可能的指数结果`n`。 由于多个测试用例可能共享相同的限制，这可以避免重复相同的测试用例`O(sqrt(n))`计算。 

位掩码`MOD - 1`每次大型操作后仅保留最低 64 位。 Python 整数不会自然溢出，因此这种显式掩码会重现所需的模数`2^64`。

 ## 边缘情况

 对于`n=1`，商分组只有一个区间。 该算法开始于`l=1`，计算`q=1`，并处理单个除数。 没有尝试访问除数零，因此自然会处理最小的情况。 

对于等指数，例如：```
Input:
1
2 2 100
```两种计算都使用相同的指数并产生相同的前缀和。 最终的异或运算产生零。 该实现无需特殊分支即可处理此问题，因为 XOR 已经具有此属性。 

对于非常大的值，例如：```
Input:
1
3 2 1000000000000
```中间算术超出了正常的有符号 64 位范围。 该算法在运算后进行屏蔽，准确保留所需的低 64 位，而不是依赖于语言溢出行为。 

对于以下情况`n`接近商边界，例如`n=10`、区间计算`r=n//q`必须准确。 如果使用了一个实现`r=l`或者错误地增加，它会跳过或重复计算除数。 这里使用的分组公式总是从`l`到`r+1`，因此每个除数恰好出现在一个区间内。
