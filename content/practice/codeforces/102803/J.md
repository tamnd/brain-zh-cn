 ## 解决方案
 ## 问题理解

 我们有一棵有根的铃儿响树。 每个节点有两个值，`a`和`b`。 根已经被修饰，但它没有任何贡献，因为它的两个值都为零。 必须在添加其父节点后添加所有其他节点。 

当一个节点`i`添加后，获得的美度为`b_i`乘以总和`a`执行此操作后仍未修饰的所有节点的值。 目标是选择一个有效的顺序来装饰所有节点，从而最大限度地提高整体美感。 

输入描述了几棵有根树。 父数组定义树结构，每个节点都包含其值对。 输出是装饰整棵树后最大可能的整体美感。 

所有测试用例的节点总数最多为`2.1 * 10^5`。 这排除了尝试许多可能的装饰顺序的方法，因为即使一棵有很多叶子的树也可能有大量的有效顺序。 我们需要一种接近线性或`O(n log n)`，其中对数可以来自优先级队列。 

一个常见的错误是只考虑具有大的节点`b`价值观。 节点的价值取决于多少`a`选择后仍然存在，所以很大`b`还不够。 另一个错误是忽略树的限制并立即对所有节点进行排序。 不能在其父节点之前选择节点。 

例如，考虑：```
3
1 1
0 0
10 1
1 100
```根有两个孩子。 首先选择第二个孩子可以获得`100 * 10 = 1000`，在选择第一个孩子时，仅给出`1 * 100`。 答案是`1000`。 仅基于节点顺序或输入顺序的策略会失败，因为两者之间的比率`b`和`a`很重要。 

另一个边缘情况是链：```
2
1
0 0
5 7
```唯一有效的顺序是根，然后是节点 2。答案是`0`，因为在放置最后一个铃之后，就没有剩余的节点了。 任何错误地添加最终节点的贡献的解决方案都会产生错误的答案。 

## 方法

 直接的解决方案将尝试所有可能的有效装饰顺序。 对于每一个订单，我们都可以模拟流程并计算美观度。 这是正确的，因为每个合法序列都经过检查。 然而，可能的订单数量呈指数增长。 一棵有许多根子节点的树已经创建了许多选择，所以暴力破解是不可能的`n = 100000`。 

关键的观察结果来自于比较两个可用节点。 假设有两个节点`x`和`y`当前都是可选的，并且都不是另一个的祖先。 让所有后来未装饰的总和`a`价值观是`R`。 

如果我们选择`x`前`y`，他们的总贡献是：```
b_x * (a_y + R) + b_y * R
```如果我们选择`y`前`x`， 这是：```
b_y * (a_x + R) + b_x * R
```在以下情况下，第一个顺序更好：```
b_x * a_y >= b_y * a_x
```这相当于：```
b_x / a_x >= b_y / a_y
```因此，在当前所有可用节点中，最好的选择始终是具有最大的节点`b / a`比率。 

树的限制意味着我们不能从一开始就对所有内容进行排序。 相反，我们维护父节点已被装饰的节点集。 从该集合中取出最佳节点后，其子节点将变得可用。 这就给出了优先级队列的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(有效订单数 * n) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算总和`a`所有节点的值。 根处理后，这代表了`a`仍然存在于装饰集之外的值。 
2. 将根的所有子节点放入按递减排序的优先级队列中`b / a`。 应首先选择比率最大的节点，因为相邻的交换参数证明提前移动它不会有什么坏处。 
3. 反复从优先级队列中删除最好的节点。 在更新剩余金额之前，添加其美丽贡献：```
b_i * (remaining a after choosing i)
```其余`a`节点修饰后减少，所以我们减去`a_i`第一的。 

1. 将所选节点的所有子节点添加到优先级队列中，因为它们现在已变得可访问。 
2. 继续，直到处理完每个节点。 

为什么它有效：

 在每一个时刻，优先级队列都恰好包含下一个可以合法选择的节点。 交换论证证明，将最大`b/a`任何其他可用节点之前的节点都不能减少答案。 因此，贪心选择在每一步都是最优的。 由于每个选定的节点都为其余节点保留了此属性，因此整个生成的顺序是最佳的。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve_case():
    n = int(input())
    parent = [0] * n
    if n > 1:
        p = list(map(int, input().split()))
        for i, x in enumerate(p, 1):
            parent[i] = x - 1

    children = [[] for _ in range(n)]
    for i in range(1, n):
        children[parent[i]].append(i)

    a = [0] * n
    b = [0] * n
    total = 0

    for i in range(n):
        a[i], b[i] = map(int, input().split())
        total += a[i]

    ans = 0
    remaining = total

    heap = []

    for v in children[0]:
        heapq.heappush(heap, (-b[v] / a[v], v))

    while heap:
        _, u = heapq.heappop(heap)

        remaining -= a[u]
        ans += b[u] * remaining

        for v in children[u]:
            heapq.heappush(heap, (-b[v] / a[v], v))

    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        out.append(str(solve_case()))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该代码将树存储为子列表，因为只有向下移动才重要。 优先级队列使用负比率，因为Python的堆是最小堆。 

在添加贡献之前，剩余的总和会减少，因为公式使用了当前节点放置后未修饰的节点。 根永远不会插入到队列中，因为它已经被处理并具有`a = b = 0`。 

Python 浮点比较在这里是安全的，因为值最多是`10000`，但使用交叉乘法的整数比较器也是可能的。 答案本身可以比 32 位整数大得多，因此 Python 的任意精度整数可以避免溢出问题。

 ## 边缘情况

 第一个边缘情况是单节点树。 根已经被装饰并且没有任何动作，所以答案是零。 该算法会处理此问题，因为优先级队列一开始为空。 

第二种边缘情况是每个节点只有一个子节点的链。 顺序没有选择，优先级队列总是恰好包含一个节点。 贪心方法减少了唯一可能的遍历。 

第三种边缘情况是当多个可用节点具有相同的值时`b/a`比率。 它们之间的任何顺序都会给出相同的成对结果，因为比较方程变得相等。 堆可以选择其中任何一个而不改变最终答案。 

最后一个重要的情况是一个节点有很大的`b`但更大的`a`。 这样的节点可能看起来很有吸引力，但过早选择它会消除大量的未来`a`价值。 比率比较通过同时考虑两种效应来防止这种错误。
