 ## 解决方案
 ## 问题理解

 每个音乐家都可以被视为一个 30 位掩码，描述了 11 月份各天的可用性。 对于给定的一天，如果音乐家当天有空，则设置相应的位，否则取消设置。 一天的权重是固定的，仅取决于它在月份中的位置，因此每一天都对应于唯一的 2 的幂。 

当我们选择一组 K 音乐家时，只有当该组中的每个音乐家当天都有空时，这一天才会对该组做出贡献。 用位术语来说，当且仅当所有选定的掩码在该位置包含 1 时，一天才起作用。 这意味着该组的最终得分恰好是 K 个选定整数的按位与。 

因此，任务简化为从 N 个数字中选择 K 个数字，以便它们的按位 AND 值尽可能大。 

N 到 200000 的约束立即排除了枚举 K 个元素的所有子集甚至组合，因为这会导致组合爆炸。 即使尝试所有具有固定 K 的组也是不可行的。 任何有效的解决方案都必须以大约 O(N log some) 或 O(30N) 的速度处理输入。 

当贪婪直觉应用不正确时，就会出现微妙的失败情况。 如果试图选择 K 个最大的数字，这不一定有效，因为“大值”与位重叠不对齐。 

例如，考虑 K = 2：```
3 numbers:
a = 111000 (binary)
b = 110111
c = 111100
```选择两个数值最大的可能会选择 b 和 c，其 AND 为`110100`。 但是选择 a 和 c 给出`111000 AND 111100 = 111000`，哪个更好。 按值排序是无关紧要的； 重叠结构很重要。 

另一个常见的错误是贪婪地相交所有数字。 如果我们对所有 N 进行 AND，我们会得到最小的可能结果，这不是必需的，因为我们可以选择大小为 K 的子集。 

## 方法

 蛮力的想法很简单：尝试 K 个音乐家的每个子集，计算他们的按位 AND，并跟踪最大结果。 这是正确的，因为它评估了问题的确切定义。 问题是子集的数量，其数量级为$\binom{N}{K}$，即使对于中等 N 也远远超出任何可行的计算。 

更结构化的观点来自于重写目标。 不要考虑组合选定的音乐家，而是考虑构建一个目标位掩码 M。如果 M 是选定组的最终 AND，则每个选定的音乐家必须包含 M 的所有位。因此问题变成找到一个掩码 M，使得至少 K 个音乐家是 M 的超集，并且 M 尽可能大。 

这种观点提出了按位贪婪策略。 我们尝试从最高位向下构造M。 假设我们已经固定了M中的某些位的前缀。当考虑是否设置下一个位时，我们只需要检查是否至少有K个音乐家包含所有当前选择的位加上这个新位。 如果是，我们保留它； 否则我们会丢弃它。 正确性来自于较高位主导该值的事实，因此必须按此顺序更早地尝试任何改进。 

关键的结构观察是单调性：如果一组音乐家支持掩码 M，那么它也支持 M 的任何子掩码。这使得可行性检查在贪婪细化下表现良好。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对子集的暴力破解 | O(N 选择 K·K) | O(1) | O(1) | 太慢了|
 | 按位贪心可行性检查 | O(30N) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将每个音乐家代码视为 30 位整数。 

1. 从等于 0 的空掩码 M 开始。这代表当前对答案的最佳猜测，最初允许所有音乐家。 
2. 从 29 到 0 迭代位位置。每个位代表具有固定贡献的一天，因此较高的位总是更有价值。 
3. 尝试设置M中的当前位，形成候选掩码M'。 这代表了强制这一天包含在最终 AND 结果中的想法。 
4. 扫描所有音乐家并统计有多少满足条件`(music_i & M') == M'`。 这会检查音乐家在 M' 当前要求的每一天是否有空。 计数代表如果我们强制执行 M'，仍有多少音乐家可以参与。 
5.如果计数至少为K，则永久接受该位并将M更新为M'。 否则丢弃该位并保持M不变。 
6. 处理完所有位后，M 就是最终答案。 

每项检查背后的中心思想是可行性。 我们并不试图在每一步中显式地选择组，只是验证在当前约束下是否仍然存在大小为 K 的有效组。 

### 为什么它有效

 在任何阶段，M 都代表一个可实现的掩码，这意味着存在一组至少 K 个音乐家，其中都包含 M。当我们尝试添加新位时，我们会问是否仍然存在满足更强要求的大小 K 的子集。 如果存在这样的子集，则保留该位不会妨碍最优性，因为它在增加价值的同时保留了可行性。 如果它不存在，则没有有效的解决方案可以将该位与已经固定的较高位一起包括在内，因此拒绝它不会删除任何最佳候选者。 这保持了 M 始终是字典顺序上最大（按位重要性）可行掩码的不变性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_with_mask(arr, mask):
    cnt = 0
    for x in arr:
        if (x & mask) == mask:
            cnt += 1
    return cnt

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))

    mask = 0

    for b in range(29, -1, -1):
        candidate = mask | (1 << b)
        if count_with_mask(arr, candidate) >= k:
            mask = candidate

    print(mask)

if __name__ == "__main__":
    solve()
```该代码准确地反映了贪婪的构造。 功能`count_with_mask`通过检查有多少音乐家完全满足候选掩模来验证候选掩模的可行性。 主循环尝试按降序激活每个位，并仅在有足够的音乐家保持有效时才提交它。 

一个微妙的实现细节是条件`(x & mask) == mask`。 这确保了候选者中设置的每个位也出现在音乐家中。 一个常见的错误是这样写`(x & mask) > 0`，它仅检查部分重叠，并且是不正确的，因为我们需要完全包含所有必需的位。

 ## 边缘情况

 当所有音乐家都相同时，每个候选位总是通过可行性检查。 该算法保留所有位并返回完整掩码，这与任何 K 子集产生相同 AND 的事实相匹配。 

当没有两个音乐家共享共同位时，每次设置任何位的尝试都会立即失败。 掩码始终保持为零，结果正确地反映了没有一天可供所有选定的音乐家使用。 

当 K 等于 N 时，该算法有效地计算所有数字的按位 AND。 每次可行性检查都要求所有音乐家满足面具，因此该过程退化为渐进交集，直接匹配问题定义。
