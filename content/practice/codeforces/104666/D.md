 ## 解决方案
 ## 问题理解

 该游戏在一个像巧克力棒一样的大矩形网格上进行。 有些细胞被污染了。 两名玩家沿着网格线重复切割当前剩余的矩形，并丢弃切割的一侧，保留另一侧作为新的活动区域。 关键规则是，如果玩家吃掉了至少含有一个受污染细胞的棋子，则该玩家立即失败。 

通过选择当前矩形的一条边，然后从该边计算切割线来指定移动。 例如，像“top X”这样的移动意味着我们在当前矩形顶部边界的第 X 行之后水平剪切，并丢弃顶部部分，保留底部。 类似地，“左X”表示垂直切割并丢弃左侧部分，依此类推。 

从游戏的角度来看，每次移动都会将当前矩形缩小为较小的轴对齐矩形，唯一禁止的结果是根据解释丢弃或保留的棋子包含污染单元。 由于该问题明确表明玩家如果吃掉受污染的方块就会失败，因此每一步都必须确保吃掉的部分不包含受污染的细胞。 

输入给出的完整初始网格大小高达 100,000 x 100,000，但最多只有 100 个污染单元。 每次移动后，我们都会交互地接收对手的移动或终端“呸！” 说明他们输了。 

这些约束立即意味着我们无法模拟完整的网格。 任何解决方案必须仅取决于受污染细胞的位置。 由于 K 至多为 100，因此任何关于削减或界限合法性的推理只需要考虑这些点。 

一种简单的方法是维护当前的矩形，并且对于每个可能的切割，扫描所有受污染的单元以检查丢弃的区域是否包含其中的任何一个。 每个移动方向最多有 10^5 个可能的切割位置和最多 100 个受污染的单元格，这变成每次移动 10^7 个检查，这已经很紧张了，并且整个交互序列很容易超出限制。 

如果假设任何切割只要不立即隔离保留区域中的受污染细胞，都是安全的，则会出现一种更微妙的故障模式。 这是不正确的，因为吃掉的区域才是重要的，并且根据方向，必须一致地处理吃掉哪一侧的解释。 即使保留的矩形是安全的，误解这一点也会导致无效的移动。 

另一种边缘情况是所有受污染的细胞都位于边界线上。 粗心的策略可能会尝试精确地沿着该线进行剪切，但由于该规则计算的是正方形，而不是网格线，因此未对齐的索引可能会将安全区域错误地移动一个单位，并导致意外包含受污染的单元格。 

## 方法

 关键的观察结果是，游戏状态完全由仍然包含所有剩余污染单元的最小轴对齐矩形决定。 一旦我们知道当前的矩形，任何有效的移动都必须缩小它，同时确保丢弃的部分不包含任何污染的单元格。 

这立即表明，唯一有意义的约束来自当前仍在矩形内“存活”的受污染细胞的极值位置。 具体来说，我们只关心受污染单元格的最小和最大行索引和列索引。 当前的安全矩形始终受这些极端的限制，因为任何更大的扩展都已经在本应提前结束游戏的区域中包含了受污染的单元格。 

因此，游戏简化为在污染集周围维持一个不断缩小的边界框。 每次移动都必须缩小这个边界框，同时避免穿过被吃部分中仍包含受污染细胞的区域。

关键思想是，由于对手也被迫做出有效的动作，因此边界框总是以受控的方式缩小。 一种获胜策略是始终紧邻受污染细胞边界框的一侧进行切割，有效地剥离安全带，直到对手被迫采取失败的行动。 

暴力方法将针对每个方向上的每条可能的切割线，通过扫描所有 K 点来测试被移除的一侧是否包含任何污染细胞。 这是正确的，但在交互下太慢了。 

相反，我们预先计算受污染单元格的四个极值坐标：最小行、最大行、最小列和最大列。 每一个有效的举动都可以通过切出这些极端之一来选择，确保我们只删除安全区域。 

这将每次移动简化为 O(1) 推理：我们总是知道最近的危险边界在哪里。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每次切割检查 O(K)，可能是 O(K * 移动) | O(K) | 太慢了|
 | 最佳| O(K) 预处理，每次移动 O(1) | O(K) | 已接受 |

 ## 算法演练

 我们使用四个值维护所有受污染单元格的边界矩形：顶部、底部、左侧和右侧。 

1. 读取所有受污染的单元格坐标并计算最小行、最大行、最小列和最大列。 这些定义了唯一对合法性重要的区域。 
2. 将当前活动矩形初始化为完整网格。 
3. 决定先玩还是后玩。 如果我们选择第二个，则立即打印“pass”并首先等待对手移动。 
4. 在每个回合中，查看当前活动矩形并将其与受污染的边界框进行比较。 
5. 如果最上面的污染行上方有安全空间，则发出移动“top X”，其中 X 是从当前顶部边界到污染区域开始之前的距离。 这仅删除安全行。 
6. 否则，如果最底部受污染行下方有安全空间，请对称发出“底部 X”。 
7. 否则，对使用“左”和“右”的列执行相同的逻辑。 
8. 每次移动后，相应地更新活动矩形并继续，直到对手失败。 

关键原因是我们总是切割保证不包含受污染细胞的区域。 由于污染区域是固定的，每次切割都会减少其周围的安全填充，而无需接触它。 

### 为什么它有效

 不变的是，活动矩形始终完全包含所有受污染单元的边界框，并且每次移动都会删除完全位于该边界框之外的条带。 由于任何动作都不会删除包含受污染细胞的区域，因此合法性得以保留。 最终，活动矩形完全折叠到边界框上，此时对手的任何进一步强制移动都必然涉及吃掉受污染的细胞，从而以对我们有利的方式结束游戏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def flush():
    sys.stdout.flush()

def move(cmd):
    print(cmd)
    flush()

R, C, K = map(int, input().split())

top = R
bottom = 1
left = C
right = 1

for _ in range(K):
    a, b = map(int, input().split())
    top = min(top, a)
    bottom = max(bottom, a)
    left = min(left, b)
    right = max(right, b)

started = False

def shrink():
    global top, bottom, left, right

    # try top
    if top > 1:
        x = top - 1
        move(f"top {x}")
        top = 1
        return True

    # try bottom
    if bottom < R:
        x = R - bottom
        move(f"bottom {x}")
        bottom = R
        return True

    # try left
    if left > 1:
        x = left - 1
        move(f"left {x}")
        left = 1
        return True

    # try right
    if right < C:
        x = C - right
        move(f"right {x}")
        right = C
        return True

    return False

# we can just play first; if we want second, print pass
# here we choose first for simplicity
# (interactive strategy does not depend on opponent)
# If required, one could read first opponent move instead.

# main loop
while True:
    if not shrink():
        break
    line = input().strip()
    if line == "yuck!":
        break
```该代码维护受污染单元格的边界框，并反复从外部删除安全条。 通过检查哪一侧仍然具有可移动的安全空间来确定性地选择每一步。 在互动问题中，每次走​​棋后的冲水至关重要，以确保法官立即收到命令。 

一个微妙的实现细节是，矩形更新假设我们总是切除整个安全带，直至污染区域的边界。 这使不变量保持简单：每次移动后，活动矩形的至少一个边界与受污染的边界框对齐。

 ### 示例 1

 我们从 4 x 6 网格开始，并在 (2,3) 和 (4,4) 处设置污染单元。 边界框为top=2、bottom=4、left=3、right=4。

 该痕迹显示，我们首先删除安全的顶部条带，然后通过删除安全的左侧条带来响应对手，逐渐将矩形向污染区域折叠。 

### 示例 2

 初始网格为 3 x 5，在 (2,3) 处有一个污染单元，因此边界为上=2、下=2、左=3、右=3。

 ## 边缘情况

 位于角落的污染单元，例如 (1,1)，强制所有安全切割仅发生在相对侧。 该算法可以处理这个问题，因为边界框立即折叠到角落，在两侧没有留下安全带。 

当所有受污染的单元格位于同一行（例如第 50 行）时，顶部和底部边界变得相同。 然后，该算法将仅执行左右切割，正确避免可能接触污染行的水平移动。 

当受污染的细胞形成垂直线时，同样的对称性适用，将运动限制为仅水平收缩。 每次切割仅删除安全条的不变性确保即使在这些退化配置中也不会产生无效的移动。
