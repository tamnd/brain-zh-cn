 ## 解决方案
 ## 问题理解

 我们得到一个无向图，表示岛屿和某些岛屿对之间的直接影响路径。 影响力是传递性的，这意味着如果岛 A 可以影响 B 并且 B 可以影响 C，那么即使没有直接边缘，A 和 C 也处于相同的连通环境中。 

每个查询都描述了特定实验“有人居住”的岛屿子集。 对于该子集，当仅考虑那些有人居住的岛屿及其之间的边缘时，我们需要确定其中存在多少个不相连的影响集群。 

用图术语来说，每个查询都会问：如果我们在给定的一组顶点上获取归纳子图，它有多少个连通分量。 

这些约束使我们不必从头开始为每个查询重新计算连接性。 最多有 100000 个节点、100000 条边和 100000 个查询，但所有查询的查询顶点总数也仅限于 100000 个。最后一个事实至关重要，因为这意味着我们无法重复扫描大量节点子集或每次查询重建完整的 DSU 结构。 在最坏的情况下，任何涉及每个查询所有节点的方法都会降级到大约 10^10 次操作，这是不可行的。 

一个简单的心理模型是为每个查询运行 DFS 或 BFS，仅标记该子集中访问过的节点。 这在逻辑上是正确的，但太慢，因为每次遍历都可能重复扫描许多边。 

当人们假设全局连接的组件就足够时，就会出现一个更微妙的陷阱。 如果我们预先计算完整图的 DSU 组件，并通过计算所选节点中存在多少个 DSU 组件来回答每个查询，我们就会忽略这样一个事实：当中间节点不存在时，连接可能会中断。 

例如，考虑链 1-2-3-4。 如果查询包含 {1, 3, 4}，则全局 DSU 表示所有节点都已连接，但在诱导子图内缺少节点 2，因此 1 是孤立的，并且 {3,4} 形成一个组件，给出答案 2，而不是 1。这表明我们必须尊重诱导连接，而不是全局连接。 

## 方法

 暴力解决方案独立处理每个查询。 对于每组节点，我们构建一个仅限于该子集的已访问数组，并从子集中的每个未访问节点运行 DFS/BFS，计算我们开始新遍历的次数。 每次遍历都会探索边并检查邻居是否属于当前查询集。 

这是正确的，因为它直接计算导出子图的连通分量。 问题是成本。 在最坏的情况下，每个查询可能包括几乎所有节点，并且每个 BFS 将遍历大多数边。 当 P 达到 100000 时，这大约变为 O(P·(N+E))，这远远超出了限制。 

关键的观察结果是，尽管有很多查询，但所有查询中出现的顶点总数总体而言很小。 这表明我们应该以一种分摊工作量的方式处理查询。 

考虑连接性的一个有用方法是通过不相交集并集结构，但我们不是在全局范围内维护它，而是在每个查询中增量激活节点。 由于我们只需要考虑查询内节点之间的边，因此我们可以临时“打开”查询的节点，通过现有边将它们联合起来，然后重置。 然而，除非我们仔细跟踪修改，否则天真地重置 DSU 的成本很高。 

标准技术是使用全局 DSU，但通过仅合并当前查询中活动的节点来避免完全重置，同时保留时间戳或标记数组。 我们确保仅当两个端点都是当前查询集的一部分时才尝试联合。 由于仅当每个边的端点出现在某个查询中时才考虑该边，因此所有查询的总工作量仍与查询大小加上与其相关的边数之和成正比。

另一个清晰的视角是使用邻接列表和具有“查询本地激活”功能的 DSU 对每个查询进行离线处理。 由于 M 的总和为 100000，因此所有查询中所有节点的迭代与输入大小呈线性关系。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的强力 DFS | O(P · (N + E)) | O(P · (N + E)) | O(N + E) | 太慢了|
 | 具有按查询激活的 DSU | O(N + E + 总 M) | O(N + E) | 已接受 |

 ## 算法演练

 我们维护图的全局邻接表。 对于每个查询，我们仅处理其列出的节点，并使用跨查询重用的 DSU 构建它们之间的连接，但我们小心地避免交叉查询污染。 

1. 读取查询列表并将其中的所有节点标记为“对此查询有效”。 这允许 O(1) 成员资格检查。 
2. 通过将每个节点设置为其自己的父节点并将大小设置为 1，仅为查询中的节点初始化 DSU 父结构。我们还在查询中维护一个节点列表以供以后清理。 
3. 迭代查询中的每个节点 u。 对于原始图中 u 的每个邻居 v，检查 v 在当前查询中是否也处于活动状态。 如果是，则在 DSU 中联合 u 和 v。 
4. 处理完所有边后，计算查询的节点中存在多少个不同的 DSU 根。 这是连接组件的数量。 
5. 在移至下一个查询之前，重置此查询中节点的活动标记。 

步骤 3 的关键思想是我们只考虑完全包含在查询集中的边。 任何接触不活动节点的边都是无关的，因为该节点不存在于导出子图中。 

### 为什么它有效

 对于每个查询，我们根据需要有效地构建归纳子图。 DSU 精确合并由该导出子图中的边连接的顶点对。 由于 DSU 保留等价闭包，因此节点的最终划分完全对应于连接的组件。 不会发生额外的合并，因为我们通过查询成员身份显式过滤边，并且不会错过任何所需的合并，因为每个有效的诱导边都会从至少一个端点处理一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, e, p = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    for _ in range(e):
        a, b = map(int, input().split())
        adj[a].append(b)
        adj[b].append(a)

    parent = list(range(n + 1))
    size = [1] * (n + 1)

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        ra, rb = find(a), find(b)
        if ra == rb:
            return
        if size[ra] < size[rb]:
            ra, rb = rb, ra
        parent[rb] = ra
        size[ra] += size[rb]

    active = [False] * (n + 1)

    for _ in range(p):
        tmp = list(map(int, input().split()))
        m = tmp[0]
        nodes = tmp[1:]

        for v in nodes:
            active[v] = True
            parent[v] = v
            size[v] = 1

        for u in nodes:
            for v in adj[u]:
                if active[v]:
                    union(u, v)

        roots = set(find(x) for x in nodes)
        print(len(roots))

        for v in nodes:
            active[v] = False

if __name__ == "__main__":
    solve()
```该解决方案构建图形一次，然后独立处理每个查询。 DSU 被重用，但仅重新初始化查询内的节点。 活动数组确保我们只合并查询集中的边。 

一个微妙的点是我们只为查询中的节点重置父指针，而不是全局重置。 这避免了每个查询的 O(N) 重置。 由于每个节点仅在出现时才重置，因此所有查询的总重置成本为 O(total M)。 

另一个细节是通过根对成分进行计数。 我们为查询中的每个节点计算 find(x) 并插入到集合中。 这与查询大小呈线性关系并且与约束一致。

| 步骤| 活动集| DSU 合并 | 组件|
 | --- | --- | --- | --- |

 | 加工边缘| 2-3-4 通过边缘链 | 联盟(3,4) | 2 |

 节点 3 和 4 连接，节点 2 隔离，因此答案为 2。 

第二个查询是 {1}。 单个节点意味着一个组件。 

第三个查询是{1,2,3,4}。 所有边均处于活动状态，形成单个连通分量，因此答案为 1。 

这证实了诱导连接与全局连接不同，尤其是在部分子集中。

5 5 4 3 2 1
```| 步骤| 活动集| DSU 合并 | 组件|
 | --- | --- | --- | --- |

 | 边缘处理 | 仅边缘 1-2 | 联盟(1,2) | 4 |

 仅节点1和2相连； 其余部分保持隔离，提供 4 个组件。 

这表明大型查询中的稀疏边缘仍然只在本地合并。

 ## 边缘情况

 第一个边缘情况是当查询包含单个节点时。 该算法激活该节点，不执行并集，并且根集恰好包含一个元素，产生输出 1。这避免了任何特殊处理，自然不符合 DSU 行为。 

第二种边缘情况是即使全局图很稠密，导出的子图也没有边缘。 在这种情况下，有源过滤器会阻止所有联合。 每个节点在初始化后仍保留其自己的父节点，因此根的数量等于查询大小，这对于完全断开的诱导图是正确的。 

第三种边缘情况是大型连通图，其中查询选择稀疏端点。 仅考虑端点均处于活动状态的边，因此即使存在全局连接，DSU 也仅合并本地相关部分。 这可以防止依赖全局连接信息而忽略丢失的中间节点的常见错误。
