 ## 解决方案
 ## 问题理解

 我们得到一个字符串，我们需要决定它是否可以通过一个非常具体的过程来构建，该过程从左到右的选择构建字符串。 该过程从空字符串开始，然后按字母顺序引入字母，从`'a'`， 然后`'b'`， 等等。 当每个新字母到达时，它必须放置在当前字符串的左端或右端，而不能放置在中间。 

因此，最终的字符串是重复获取下一个字母字符并决定它是到达已构建的内容的左边界还是右边界的结果。 问题是给定的字符串是否可以通过这些边界插入的某些序列生成。 

重要的结构约束是每个字母`'a'`到`'z'`在构建过程中最多出现一次，并且一旦放置了一个字母，它就成为不断增长的块的一部分，其末端是唯一的活动插入点。 

每个测试用例的输入大小最多为 26 个字符，这会立即排除任何大量优化或组合搜索的需要。 即使多次检查每个字符的解决方案也是安全的，因为 26 是常数。 对于多达 10^4 个测试用例，我们仍然只执行大约 2.6 × 10^5 字符操作，这是微不足道的。 

主要的非明显失败案例来自看起来局部一致但无法通过有效边界插入形成的字符串。 

一个典型的例子是`"acb"`。 乍一看似乎有道理，因为它在字母表的前缀中包含连续的字母，但是没有办法插入`'c'`后`'a'`和`'b'`已经定位为`'c'`只能走到一个终点。 另一个例子是`"ca"`， 在哪里`'a'`和`'c'`违反规则`'b'`必须出现在之前`'c'`在构建过程中，即使它不存在于最终字符串中。 

另一个微妙的情况是`"aa"`。 尽管重复项看起来可能是由于在不同末端插入相同的字母两次而产生的，但该过程显式地引入了每个字母一次，因此重复会立即使字符串无效。 

## 方法

 暴力方法会尝试模拟构建字符串的所有可能方法。 对于每个测试用例，我们可以递归地尝试放置`'a'`在任一端，然后`'b'`在任一端，依此类推，并检查我们是否可以到达目标字符串。 每一步都会使可能性的数量加倍，因此这变成了 2^n 个状态。 尽管 n 至多为 26，但 2^26 已经很大，并且对于 10^4 测试用例，这种方法在概念上变得过于昂贵且不必要。 

关键的观察结果是，该过程在必须出现哪些字母方面是完全确定的：字符串必须恰好包含从`'a'`，并且每一步都会删除下一个预期字符的最左边或最右边的剩余有效位置。 这意味着我们可以逆转该过程而不是构建它。 

我们不是向前构建字符串，而是重复识别当前最小的预期字符（从`'a'`) 并检查它是否位于当前字符串的任一端。 如果是，我们将其删除并继续。 如果任何一点不在两端，则施工是不可能的。 

这将问题从对布局的指数搜索减少为每个测试用例的线性贪婪检查。

 ## 算法演练

 我们将字符串视为一个动态区间，当我们按字母顺序剥离字符时，该区间会缩小。 

1. 初始化两个指针，一个在字符串的左端，一个在右端。 将预期字符设置为`'a'`。 这反映出该建设必须引入`'a'`第一的。 
2. 当预期字符未超过字符串中存在的最大字符时，将其与当前间隔两端的字符进行比较。 
3. 如果左端与预期字符匹配，则向内移动左指针并将预期字符前进到下一个字母。 这对应于在构造期间将字符插入到左侧的情况。 
4. 否则，如果右端与预期字符匹配，则将右指针向内移动并前进预期字符。 这对应于右侧的插入。 
5. 如果两端都不匹配预期字符，则终止并返回 NO，因为没有有效的构造步骤可以将该字符放入内部。 
6. 如果所有字符都按顺序成功消耗，则返回YES。 

这种贪婪选择有效的原因是，在每一步中，下一个所需的字符都必须在其中一个边界处暴露。 任何有效的结构都必须使其在插入时可访问，因为所有较小的字符都已被放置并从考虑中删除。 

### 为什么它有效

 在有效构造中的任何点，剩余的子字符串完全对应于由尚未放置的字符形成的连续块。 下一个所需的字符是最小的未使用的字母，并且它必须是在该阶段的剩余结构中最后添加的。 因此它必须位于当前间隔的两端之一。 如果它不在任一端，则先前的左或右插入序列都不可能在不违反构造顺序的情况下将其隐藏在中间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    l, r = 0, len(s) - 1
    
    expected = ord('a')
    ok = True
    
    while l <= r:
        if s[l] == chr(expected):
            l += 1
            expected += 1
        elif s[r] == chr(expected):
            r -= 1
            expected += 1
        else:
            ok = False
            break
    
    print("YES" if ok else "NO")
```其实现直接反映了贪婪的思想。 这两个指针维护尚未验证的字符串的当前活动段。 这`expected`变量跟踪下一个所需的字母字符。 每次迭代仅消耗一个字符，确保每个测试用例的线性时间。 两端的检查就足够了，因为构造规则只允许在边界处插入。 

一个常见的错误是试图向前模拟构造，这会导致放置选择的模糊性。 颠倒这个过程就可以完全消除这种歧义。

 ## 边缘情况

 对于`"a"`，算法集`l = r = 0`，看到`'a'`在左边，消耗它，并立即成功完成。 这证实了单字符字符串是非常有效的。 

为了`"aa"`, 第一个比较匹配`'a'`在一端并消耗它，但第二个`'a'`无法匹配任何预期的下一个字符，因为预期的序列移动到`'b'`。 由于第二个字符仍然是`'a'`，该过程失败，正确拒绝重复项。 

为了`"z"`单独而言，预期的字符开始于`'a'`，但两端都不匹配，因此算法立即拒绝，反映出在构造中不可能跳过较早的字母表字母。
