 ## 解决方案
 ## 问题理解

 我们给定一个序列$x_1, x_2, \dots, x_n$。 我们的任务是构建另一个序列$y_1, y_2, \dots, y_n$这样当我们按元素对它们进行异或时，得到的序列$$a_i = x_i \oplus y_i$$具有单调位结构：设置的每个位$a_i$还必须设置在$a_{i+1}$。 按位计算，这意味着$$a_i \& a_{i+1} = a_i.$$所以顺序$a_i$在设置位的意义上是非递减的：一旦某个位变为 1，以后就永远不会变为 0。 

我们不建造$a_i$直接地。 相反，我们必须选择$y_i$，并且在所有有效选择中，我们必须按字典顺序最小化序列。 

关键的相互作用是每个$y_i$控制$a_i$通过异或。 由于 XOR 独立翻转位，每个位置$i$可以被认为是选择$a_i$，然后推导$y_i = a_i \oplus x_i$，但有一个约束条件，即结果$a$-序列必须满足生长条件。 

限制条件很大：总计$n$跨测试最多可达$2 \cdot 10^5$。 这迫使每次测试都得到线性或近线性的解决方案。 任何尝试考虑所有可能的位模式或回溯选择的方法都会立即变得太慢。 

一种幼稚的方法会尝试构建$y_i$贪婪地但每次都检查完整前缀的有效性，或者甚至尝试在保持一致性的同时独立选择每个位。 问题在于，约束通过位持久性将所有位置耦合起来，因此局部决策可能会破坏未来的可行性。 

贪婪最小化时会出现一个简单的失败案例$y_i$独立地：```
x = [1, 2]
```如果我们选择$y_1 = 0$， 然后$a_1 = 1$。 在$i=2$,如果我们再次选择$y_2 = 0$， 然后$a_2 = 2$，我们得到$1 \& 2 = 0 \neq 1$， 无效的。 解决这个问题需要预测未来职位的限制。 

所以主要的困难是每个$a_i$必须是先前的超集（按位意义），同时仍然保持$y_i$按字典顺序排列较小。 

## 方法

 蛮力的想法就是尝试所有可能的方法$y_1$, 计算$a_1$，然后强制执行每个后续的$a_i$必须是所有先前的超集$a$的。 在步骤$i$，我们会尝试所有$y_i$这样$a_i = x_i \oplus y_i$满足日益增长的约束$a_{i-1}$。 这意味着枚举每个位置的所有位掩码，并为每个候选检查兼容性。 

由于每个$x_i < 2^{30}$， 每个$y_i$也位于 30 位空间中，放弃$2^{30}$每个位置的可能性。 即使通过约束进行修剪，仍然会留下指数搜索。 这显然是不可行的。 

关键的观察结果是对$a_i$就位包含而言是单调的：一旦某个位在某些中变为 1$a_i$，它必须永远保持为 1。 这建议维护一个全局位掩码$S$，表示之前已强制为 1 的所有位$a$-价值观。 

在位置$i$，我们必须确保$a_i$包含所有位$S$。 按字典顺序排列的最小选择$y_i$对应于制作$a_i$尽可能小，同时仍然包括$S$。 自从$a_i = x_i \oplus y_i$，我们可以改为决定$a_i$如：

 - 所有位$S$必须是 1
 - 如果额外的位有助于未来的约束，则可以选择为 1，但任何额外的 1 只会损害字典顺序上的后续选择

 因此，最优策略是强制执行$a_i = x_i \,|\, S$。 之前步骤已经需要的任何位都必须出现，引入新位只会增加$S$，这将恶化未来的约束，并可能迫使更大的值按字典顺​​序排列$y$。 

一次$a_i$已修复，我们恢复$y_i = a_i \oplus x_i$，并更新$S = S \,|\, a_i$。 

这将问题简化为维护位掩码的单个从左到右传递。

 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化位掩码$S = 0$。 这代表在所有未来都必须保持存在的位$a_i$。 
2. 从左到右迭代序列。 在位置$i$，计算候选者$$a_i = x_i \,|\, S.$$这确保了所有先前需要的位都被保留。 
3. 计算$y_i = a_i \oplus x_i$。 这是最小值$y_i$改变$x_i$进入$a_i$，因为 XOR 恰好翻转了其中的位$x_i$和$a_i$不同。 
4.更新全局约束：$$S = S \,|\, a_i.$$这扩展了未来必须保持存在的位组。 
5、输出$y_i$立即执行，因为未来的决策不会影响过去的值。 

### 为什么它有效

 不变的是处理后的位置$i$，当前集合$S$等于所有构造的按位并集$a_1, \dots, a_i$。 任何有效的未来$a_j$必须包含所有位$S$，否则它将违反该位首次出现的某个较早索引的增长条件。 

每一步，选择$a_i = x_i | S$给出尽可能最小的有效值$a_i$在这个约束下。 任何较小的选择都会错过一点$S$并打破有效性。 任何更大的选择都会引入不必要的位，这会增加$y_i$或强制将来的更新只能增加字典顺序。 由于字典顺序比较取决于最早的不同位置，因此最小化每个$y_i$在最严格的有效约束下产生全局最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        x = list(map(int, input().split()))
        
        S = 0
        res = []
        
        for xi in x:
            ai = xi | S
            yi = ai ^ xi
            res.append(str(yi))
            S |= ai
        
        out.append(" ".join(res))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现保持了不断发展的约束掩码`S`。 在每一步中，我们构造最小的有效值$a_i$通过或与`S`，然后推导$y_i$通过异或。 更新内容`S |= a_i`确保所有曾经出现过的位$a_i$为序列的其余部分保留。 

一个微妙的点是，我们永远不需要明确检查生长条件，因为构建`S`感应地保证它。 每个`a_i`已经包含所有先前的位，所以`a_{i-1} & a_i = a_{i-1}`自动保持。

 ## 边缘情况

 一种边缘情况是所有位最初都为零。 用于输入`x = [0, 0, 0]`，算法保持`S = 0`，所以每一个`a_i = 0`和每一个`y_i = 0`。 由于所有面具都是相同的，因此生长条件是微不足道的。 

当早期元素引入后面元素不包含的高位时，会出现另一种边缘情况。 为了`x = [1, 2, 4]`，掩码增长如下：第一步之后`S = 1`，迫使第二个`a_2 = 3`， 然后`S = 3`，最后`a_3 = 7`。 该算法正确地膨胀后面的值以保留前面的位，即使在原始值减少时也确保单调位包含。 

最后一个微妙的情况是单元素序列。 由于元素之间没有约束，答案很简单$y_1 = 0$，因为选择$a_1 = x_1$始终有效并最小化 XOR。
