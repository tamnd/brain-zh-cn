 ## 问题理解

 我们得到了几个独立的测试用例。 在每种情况下，我们都会收到一份运动员优势列表，并且必须将运动员分为两个非空组，以便一组贡献其最大值，另一组贡献其最小值，并且这两个值之间的绝对差异尽可能小。 

重新表述目标的一个有用方法是，我们尝试将值的多重集分成两部分，以便两部分之间的边界在值空间方面尽可能紧密。 一组将包含一些优势子集，我们只关心其最大值，而另一组仅贡献其最小值。 除了保留这两个极端之外，每个组内其余元素的实际成员资格不会影响分数。 

限制很小。 每个测试用例最多有 50 个元素，最多有 1000 个测试用例。 这立即排除了每个测试用例的任何指数分区策略。 即使每个测试用例都是二次的解决方案也是安全的，因为 50 的平方仅需要 2500 次操作。 

主要的微妙之处在于分组不受位置或顺序的限制，仅受值选择的限制。 这意味着基于输入数组中的邻接性的任何推理都是无关紧要的，只有值的排序顺序才重要。 

一个常见的错误是尝试贪婪地分配元素而不进行排序。 例如，人们可能会尝试通过交替分配或围绕索引中值进行拆分来构建两个集合。 但这会失败，因为最优性取决于数字接近度，而不是原始顺序。 

当假设最佳分割位于中值附近时，会出现另一种故障模式。 这并不总是正确的，因为重复或不均匀的间隙可以使不同的切割达到最佳效果。 例如，如果值为`[1, 2, 100, 101]`，在 2 到 100 之间分割显然是最佳的，但如果值是`[1, 2, 3, 100]`，最好的分割是在 3 到 100 之间，而不是在中值索引附近。 

## 方法

 暴力方法是尝试将数组的每个可能的分区分成两个非空集合。 对于每个分区，计算一组的最大值和另一组的最小值，然后评估绝对差。 有`2^n`可能的分区，对于每个分区，我们最多需要`O(n)`计算最大值和最小值，从而导致`O(n·2^n)`每个测试用例的复杂性。 和`n = 50`，这远远超出了可行的限度。 

关键的观察结果是该值仅取决于排序顺序中两个集合之间的边界。 一旦我们对数组进行排序，我们就可以考虑选择一个分割点来确定哪些值进入左侧组，哪些值进入右侧组。 任何最优划分都可以转换为 A 组中的所有元素都小于或等于 B 组中的所有元素的划分。如果违反此属性，交换元素只会改善或保持目标。 

排序后，候选答案减少为检查排序数组中的所有相邻对。 如果我们在职位之间分开`i`和`i+1`，那么最好的贡献是`|s[i] - s[i+1]|`，因为 A 组可以结束于`s[i]`B组可以从`s[i+1]`。 任何其他引入更大差距的任务只会增加差距。 

因此，问题归结为寻找排序数组中连续元素之间的最小差异。

 | ---| ---| ---| ---|
 | 蛮力 | O(n·2^n) | O(n·2^n) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 阅读当前测试用例的优势列表。 目标是准备数据，以便比较反映值的接近度而不是输入顺序。 
2. 按非降序对数组进行排序。 此步骤至关重要，因为它将值空间中所有潜在的最佳分割彼此相邻对齐。 如果不进行排序，相邻的差异就没有意义。 
3. 初始化变量`best`具有很大的价值。 这将存储有效分割边界之间发现的最小差异。 
4. 从索引 1 到 n−1 迭代已排序的数组。 在每个位置，计算当前元素与前一个元素之间的差异。 这表示在这两个值之间拆分数组的成本。 
5. 更新`best`每当发现较小的差异时。 这确保我们始终跟踪两组之间尽可能紧密的分离。 
6.处理完所有相邻对后，输出`best`作为测试用例的答案。 

### 为什么它有效

 排序后，任何有效的分区都可以看作是选择一个阈值，将数组分成两个非空部分。 分区的值仅取决于左侧的最大元素和右侧的最小元素。 这种对之间的最小可能间隙必须出现在按排序顺序的两个连续元素之间，因为任何较大的跳跃都会跳过更接近的候选对。 因此，扫描相邻差异就足以保证最优分割。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = list(map(int, input().split()))
    
    s.sort()
    
    best = float('inf')
    for i in range(1, n):
        best = min(best, s[i] - s[i - 1])
    
    print(best)
```解决方案首先对每个测试用例进行排序，这是使问题在值空间中一维的结构变换。 相邻对上的循环直接编码唯一有意义的分割点。 

减法`s[i] - s[i - 1]`是安全的，因为数组已排序，因此差值始终为非负数，并表示这两个元素之间拆分的确切成本。 

的初始化`best`with infinity 避免了第一次比较时的任何特殊情况处理。

 ## 边缘情况

 一种边缘情况是所有值都相同。 用于输入`[5, 5, 5, 5]`，排序保持不变，每个相邻差值为零。 该算法正确返回零，因为任何分割都会在组之间产生相同的最大值和最小值。 

另一种情况是最佳分裂不在极端附近而是在集群结构的中间，例如`[1, 100, 101, 102, 200]`。 排序给出相同的序列，相邻间隙最小的是`100`和`101`，它正确地表示了最佳分区边界。 

最后一种情况是最小可能的输入大小`n = 2`。 该算法执行一次比较并返回仅有的两个元素之间的差异，这是唯一有效的分割。
