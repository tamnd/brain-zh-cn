 ## 问题理解

 我们从所有长度为二进制字符串的完整空间开始`m`，按标准字典顺序排序，相当于将它们排序为固定长度的二进制数`0...0`最多`1...1`。 从这个完整的有序集中，删除最多 100 个字符串的小集合。 在这些删除之后，我们概念性地查看剩余的字符串，按字典顺序再次对它们进行排序，并选择中间元素，其中“中间”被定义为剩余 k 个字符串中索引 ⌊(k−1)/2⌋ 处的元素。 

思考结构的一个有用方法是，完整的集合就是区间`[0, 2^m − 1]`，解释为带有前导零的二进制数。 删除字符串会从这个非常大的有序宇宙中删除最多 100 个点。 任务是在不构建或排序整个集合的情况下确定剩余内容的中位数。 

约束是关键信号。 长度`m`可以大到 60，这使得`2^m`天文数字般大，因此任何迭代所有字符串的方法都是不可能的。 然而，删除的元素数量很少，每个测试用例最多 100 个，并且测试的总输入大小是有限的。 这种不对称性强烈表明，答案取决于移除如何在全局顺序中改变位置，而不是枚举状态。 

一个天真的方法是显式生成所有`2^m`字符串，删除禁止的字符串，排序并选择中位数。 这会立即失败，因为即使对于`m = 60`，宇宙的大小远远超出了任何计算极限。 

另一个微妙的陷阱是尝试通过计算有多少有效字符串小于候选字符串来检查排名，从而对答案进行二分搜索。 如果天真的实现，这仍然需要迭代所有`2^m`可能性或模拟大量计数效率低下。 正确的方法必须避免完全接触整个空间。 

## 方法

 暴力破解的观点很简单：枚举所有长度的二进制字符串`m`，删除禁止的，对剩余列表进行排序，然后选择中间的。 这在概念上是有效的，因为字典顺序与二进制表示的数字顺序相匹配。 然而，成本是指数级的：产生`2^60`候选人是不可能的，甚至存储它们也是不可行的。 

关键的观察是我们永远不需要全套。 我们只需要知道候选位置之前有多少个有效字符串。 由于只删除了最多 100 个字符串，所以补码的结构就基本完成了。 每个删除的字符串只会在原本连续的顺序中产生一个小“间隙”。 

这表明要考虑几乎整个时间间隔内的订单统计数据。 我们可以二分搜索范围内的答案，而不是迭代所有候选者`[0, 2^m - 1]`。 对于候选人号码`x`，我们计算有多少个有效字符串 ≤ x。 这简直就是`(x + 1) - count_removed_leq(x)`。 自从`n ≤ 100`，计算删除的元素 ≤ x 的时间复杂度为 O(n)，使得每次检查都很快。 

60 位空间上的二分查找最多需要 60 次迭代，每次迭代的成本为 O(n)，因此总数非常小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^m log 2^m) | O(2^m log 2^m) | O(2^m) | O(2^m) | 不可能|
 | 最佳 | O(n log 2^m) | O(n log 2^m) | O(n) | 已接受 |

 ## 算法演练

 我们将每个二进制字符串视为 60 位整数。 

1. 将所有删除的字符串转换为整数。 这允许使用数字顺序进行直接比较，由于固定长度，数字顺序与字典顺序匹配。 这一步很重要，因为它将字符串比较变成了算术比较。 
2. 对删除的值进行排序。 排序可以使用二分搜索实现快速前缀计数。 
3. 定义函数`removed_leq(x)`使用二分搜索对已排序的已删除数组返回多少已删除的数字 ≤ x。 这使我们能够快速访问“x 之前的前缀中有多少个禁止值”。 
4. 定义`valid_leq(x) = (x + 1) - removed_leq(x)`。 这代表有多少个有效字符串`[0, x]`。 
5. 计算目标排名`target = (2^m - n - 1) // 2`。 这是从零开始的索引中的中位数索引。 
6.二分查找最小`x`这样`valid_leq(x) > target`。 那`x`正是中位数字符串。 

二分查找适用于整个数字范围`[0, 2^m - 1]`，这是安全的，因为所有有效字符串都位于其中。 

### 为什么它有效

 功能`valid_leq(x)`是单调的`x`，因为增加`x`只能增加前缀中有效字符串的数量。 这保证了二分查找是有效的。 每个删除的字符串都会从前缀计数中减去一个点，因此与完整前缀的偏差`[0, x]`始终恰好是其中禁止元素的数量。 因此，我们无需枚举集合即可恢复准确的排名信息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def to_int(s):
    return int(s, 2)

def count_leq(arr, x):
    # number of elements <= x in sorted arr
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] <= x:
            lo = mid + 1
        else:
            hi = mid
    return lo

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        rem = [to_int(input().strip()) for _ in range(n)]
        rem.sort()

        total = (1 << m)
        k = total - n
        target = (k - 1) // 2

        def valid_leq(x):
            return (x + 1) - count_leq(rem, x)

        lo, hi = 0, (1 << m) - 1
        ans = 0

        while lo <= hi:
            mid = (lo + hi) // 2
            if valid_leq(mid) > target:
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        s = bin(ans)[2:].zfill(m)
        print(s)

if __name__ == "__main__":
    solve()
```该解决方案依赖于将二进制字符串视为整数，这消除了所有字典编排的复杂性。 排序的移除列表仅用于有效地对排除进行计数。 二分搜索可以找到准确的排名位置，而无需构建完整的集合。 

一个微妙的实现细节是填充`zfill(m)`，因为数字转换会删除前导零，但输出必须保留固定长度。 另一个重要的一点是使用`x + 1`在`valid_leq(x)`，这确保了包含范围内的正确计数。

 ## 边缘情况

 关键的边缘情况是中位数紧邻已删除的数字。 例如，如果`m = 3`我们删除`011`，范围围绕单个缺失点进行分割。 该算法仍然有效，因为前缀计数自然会跳过缺失值，而不需要显式间隙处理。 

另一种情况是删除的值聚集在范围的开头。 假设我们删除`000`,`001`,`010`。 前缀函数`valid_leq(x)`正确压缩早期段，以便二分搜索从第一个有效块有效开始`011`。 尽管数字差距很大，但计数调整与删除数量保持线性关系，因此保留了正确性。 

最后，当`n = 0`，答案就是整个范围的中间，二分查找也能找到，因为`removed_leq(x)`始终为零，结构简化为纯粹的计数`[0, 2^m - 1]`。
