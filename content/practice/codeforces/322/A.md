[CF 322A - 夏尔和跳舞](https://codeforces.com/problemset/problem/322/A)

 **标签：** 贪婪
 **求解时间：** 1m 3s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 该任务描述了一个舞蹈室，其中每场表演都只涉及一个男孩和一个女孩。 参与者从没有任何经验开始，并且在每次舞蹈期间，两个人中至少有一个必须是第一次跳舞。 换句话说，每一对必须至少包括一名从未参加过之前任何舞蹈的参与者。 

我们给定了男孩和女孩的数量，我们需要构建一系列尽可能长的有效舞蹈，同时尊重这一限制。 每支舞蹈都不是独立的，因为一旦一个人参与了，在以后的配对中可能就不再满足“第一次”的条件，所以早期的选择直接影响到后面可能发生的事情。 

界限很小，两个计数都达到 100。这立即排除了对子集进行大量优化或搜索的任何需要。 即使是 O(n²) 或 O(nm) 构造在时间上也是微不足道的，因此真正的困难不是效率，而是找到避免意外阻止未来有效移动的结构。 

一种幼稚的方法是重复选择任何有效的对并贪婪地继续。 当所选对中的两个参与者之前都已经被使用过时，就会出现微妙的故障模式。 例如，如果我们将两个已经使用过的人配对，则会立即违反规则并且构造会中断。 另一种失败模式是一组“新”参与者过早地筋疲力尽，而另一组却没有得到充分利用，从而减少了可完成的舞蹈总数。 

关键的困难是确保我们永远不会“浪费”过早介绍新参与者的机会，以免妨碍以后的有效配对。 

## 方法

 暴力策略将模拟所有可能的有效序列。 在每一步中，我们都可以尝试每个未使用或以前使用过的仍然满足规则的配对并递归。 虽然原则上是正确的，但它很快就会变成指数，因为每个状态都会分支到许多可能的配对。 即使 n 和 m 约为 100，序列的数量也会爆炸，因为每个决策都会改变哪些参与者保持“新”状态以及未来转换的有效性。 

结构洞察是，每一种舞蹈都贡献至少一个以前未使用的参与者。 这意味着舞蹈的数量严格取决于我们可以介绍多少新人。 一旦两组都被部分消耗，最好的策略是尽可能长时间地在每支舞蹈中持续引入一名新参与者。 任何提前引入两个新参与者的偏差都无济于事，因为它减少了未来可用的“新”贡献池。 

这导致了我们首先将一个男孩和一个女孩“固定”在一起的结构。 之后，我们系统地将剩余的男孩与固定的女孩配对，不断引入新的男孩，然后将剩余的女孩与固定的男孩配对，不断引入新的女孩。 这保证了在初始配对后每一步都会引入一个新参与者，这是最佳的。

 ## 算法演练

1. 选择一男一女作为初始主播，安排他们先一起跳舞。 这确保了双方至少有一个“已使用”的参与者，这为剩余的构建提供了灵活性。 
2. 将选定的女孩固定为可重复使用的伙伴，并将她与其他所有男孩配对。 这些舞蹈中的每一个都会引入一个新男孩，而女孩之前已经被使用过，因此约束仍然满足。 
3. 将选定的男孩固定为可重复使用的伙伴，并将他与除第一步中已使用的女孩之外的所有剩余女孩配对。 这些舞蹈中的每一个都会引入一个新的女孩，而男孩已经被使用，保持规则有效。 
4. 按顺序输出所有记录对。 

关键思想是，在初始配对之后，我们交替哪一方贡献新参与者，同时在另一方保留一个固定的“旧”参与者。 

### 为什么它有效

 在第一步之后的每一步中，两人中恰好有一个参与者以前从未跳舞过。 这确保了每一个舞蹈都满足规则。 该结构还保证我们永远不会过早地用完有效配对，因为每个未使用的男孩最终都会配对一次，每个未使用的女孩也会配对一次。 由于每个新参与者都作为配对的“新鲜”一方被消耗一次，因此没有任何配置可以在不违反约束的情况下产生更多的舞蹈。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    res = []
    
    # Step 1: anchor pair
    res.append((1, 1))
    
    # Step 2: use girl 1 with remaining boys
    for i in range(2, n + 1):
        res.append((i, 1))
    
    # Step 3: use boy 1 with remaining girls
    for j in range(2, m + 1):
        res.append((1, j))
    
    print(len(res))
    for a, b in res:
        print(a, b)

if __name__ == "__main__":
    solve()
```该解决方案明确地构建时间表而不是搜索它。 第一对将两个参与者初始化为“已使用”，这解锁了安全地重用任一方的能力。 男孩的循环使女孩 1 保持固定，确保每个新男孩都贡献所需的新颖性。 第二个循环反映了这个想法，固定了男孩 1，同时引入了所有剩余的女孩。 

顺序很重要，因为反转循环对于正确性并不重要，但初始锚点必须首先发生，以确保后续步骤中至少存在一个重用的参与者。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + m) | 每个男孩和女孩在初始化后至多被用于一个构造步骤 |
 | 空间| O(1) | O(1) | 仅存储输出列表，不存储取决于输入大小的辅助结构 |

 这些限制允许每组最多 100 名参与者，因此线性构建在时间和内存方面都很重要。 输出大小也受 n + m 限制，足够小可以直接打印。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    n, m = map(int, input().split())
    res = [(1, 1)]
    for i in range(2, n + 1):
        res.append((i, 1))
    for j in range(2, m + 1):
        res.append((1, j))
    print(len(res))
    for a, b in res:
        print(a, b)

# provided sample
assert run("2 1\n") == "2\n1 1\n2 1"

# custom cases

assert run("5 1\n") == "5\n1 1\n2 1\n3 1\n4 1\n5 1", "single girl"
assert run("3 3\n") == "5\n1 1\n2 1\n3 1\n1 2\n1 3", "balanced case"

 ## 边缘情况

 当只有一个男孩或只有一个女孩时，该算法仍然有效，因为第一次配对立即使唯一的参与者可以重复使用，并且所有剩余的舞蹈必须在介绍另一方时重复使用该固定的人。 例如，使用输入`1 4`，序列对`(1,1), (1,2), (1,3), (1,4)`自然产生，每一步都会引入一个新女孩，满足规则。 

当n和m都为1时，只能跳一支舞。 该算法准确地产生`(1,1)`并停止，因为没有剩余的参与者来延长序列。
