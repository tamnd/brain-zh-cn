 ## 解决方案
 ## 问题理解

 我们获得了三个独立的物品供应，每个物品代表固定颜色的花朵。 我们可以用两种完全不同的方式用这些材料制作花束。 一种类型的花束消耗三朵单一颜色的花，而另一种类型则消耗每种颜色的一朵花。 

任务是选择任意的花束排列顺序，使得没有花被重复使用，并且花束总数尽可能多。 该决策不受花束排序的限制，仅受如何在两种竞争的消费模式之间分配有限资源的限制。 

这些约束允许每种颜色计数最多为 10^9，这排除了任何尝试探索花束类型之间花朵分布的模拟。 任何以简单的方式迭代混合花束的可能分配的解决方案都会在输入值的大小上退化为线性或更糟，这是不可行的。 

一个微妙的困难来自于两种花束类型之间的相互作用。 混合花束同时减少所有三个计数，而单色花束仅减少一个维度。 诸如“始终首先获取尽可能多的混合花束”之类的天真贪婪的选择可能会失败，因为它可能会破坏以后形成许多单色三元组的机会。 例如，如果计数不平衡（如 (1, 1, 100)），则取出一束混合花束会立即移除唯一可用的红色和绿色花朵，但如果所有颜色之间存在更结构化的平衡，那么这两种花朵可能会更好地保留。 

真正的问题是，最优策略仅取决于计数模小偏移，因为每个单色花束都会将颜色减少 3，而每个混合花束都会将所有颜色减少 1。这会创建一个结构，其中仅三个计数的相对对齐很重要，而不是它们的绝对大小。 

## 方法

 蛮力方法会尝试决定采用多少混合花束，例如 x，然后从剩余计数中计算出单色花束的最佳可能数量。 对于 x 的每个选择，我们将从所有三种颜色中减去 x，然后除以 3。由于 x 的范围可以达到 min(r, g, b)，这会导致 O(min(r, g, b)) 的可能性，当值达到 10^9 时，这是完全不可行的。 

关键的见解是混合花束的决策空间不需要在整个范围内进行探索。 每个混合花束均等地减少所有三个计数，因此重要的是计数相对于彼此移位时的余数结构。 在减去混合花束的公共数量之后，至少其中一个计数变小，并且该小值有效地决定了系统的配置。 

这导致观察到最佳解决方案必须非常接近三种状态之一：我们要么进行 0、1 或 2 次初始调整，其中我们“牺牲”少量的花来改变奇偶对齐，然后贪婪地采取尽可能多的混合花束。 之后，所有剩余的花朵都独立地用于单色三元组。 尝试所有三个偏移就足够了，因为将混合花束的数量增加 3 只会将每种颜色减少 3，这不会改变剩余划分为三元组的结构。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解混合计数 | O(min(r, g, b)) | O(1) | O(1) | 太慢了 |
 | 尝试 3 个偏移 + 贪婪 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 考虑到我们可以通过预先删除 0、1 或 2 个混合花束来调整初始状态。 这样做是因为最佳配置取决于重复归约后三个值如何以模 3 对齐。 
2. 对于 {0, 1, 2} 中的每个偏移值 x，从 r、g 和 b 中减去 x，但前提是全部都保持非负。 这模拟了在提交批量操作之前强制进行不同对齐的想法。 
3. 对于调整后的值，计算我们可以形成多少个混合花束，即 min(r, g, b)。 取那么多并从所有三种颜色中减去它。 此步骤最大限度地利用了跨色资源，因为每个这样的花束同时减少了所有限制。 
4. 移除所有可能的混合花束后，使用地板除以 3 计算可以从每个剩余池中形成多少个单色花束。 
5. 对该配置的所有花束计数求和。 
6. 取所有三个偏移量的最大结果。 

### 为什么它有效

 该过程根据我们最初将所有颜色移动到一起的次数将解决方案空间分成残基类别。 一旦这种对齐方式得到解决，获取所有可能的混合花束就变得最佳，因为任何剩余的不平衡只能通过同时消耗所有颜色中的一个单位来解决。 在那之后，每种颜色在除以 3 的情况下独立演化，颜色之间不再有进一步的相互作用可以改善结果。 这确保了每个可行的最佳结构都由三个测试的比对之一表示。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    r, g, b = map(int, input().split())
    
    ans = 0
    
    for shift in range(3):
        rr, gg, bb = r - shift, g - shift, b - shift
        if rr < 0 or gg < 0 or bb < 0:
            continue
        
        # take as many mixing bouquets as possible
        mix = min(rr, gg, bb)
        rr -= mix
        gg -= mix
        bb -= mix
        
        # then take single-color bouquets
        total = mix + rr // 3 + gg // 3 + bb // 3
        ans = max(ans, total)
    
    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先尝试对应于系统不同对齐状态的所有三个可能的初始偏移。 对于每个状态，它贪婪地提取尽可能多的混合花束，因为它们平等地消耗所有三种资源，从而以最有效的方式减少不平衡。 在此稳定步骤之后，每种剩余颜色只能通过三个一组进行贡献，因此整数除以 3 给出了附加花束的确切最大数量。 

三个偏移量的最大值确保我们不会错过稍微不同的起始对齐会产生更好的长期配置的情况。

import sys, io

def run(inp: str) -> str:

 ## 边缘情况

 像这样的案例`3 0 0`表明混合花束是不可能的，算法自然会退回到仅单色三元组。 对于移位 0，我们得到零混合和一束有效的红色花束，而其他移位由于负值而无效。 这证实了算法不会在不可能的情况下错误地强制混合。 

为了`1 1 1`，班次0状态立即产生一束混合花束并消除所有花，而其他班次无效。 该算法正确地认识到没有任何单色分组比跨色组合更好，并且在正确对齐时实现了最大值。
