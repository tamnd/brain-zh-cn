 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景，其中 Gagamboy 需要购买几种化学类型中的每一种一公斤。 有多个在线卖家，每个卖家都出售每种化学品，但价格取决于化学品和卖家。 

不同之处在于，无论您从卖家那里购买了多少种不同的化学品，从卖家处订购都会触发该卖家支付固定的运费。 因此，如果您决定从卖家那里购买哪怕是一件商品，您只需支付一次运费，然后您就可以以相同的费用捆绑该卖家的任何化学品子集。 

每个测试用例的任务是将每种化学品准确地分配给一个或多个卖家，允许不同的化学品来自不同的卖家，同时最小化由商品价格加上每个卖家的激活费组成的总成本。 

从结构意义上来说，这些限制比原始尺寸上的限制要小。 每个测试用例的价格矩阵中最多有 250 个单元格，这意味着化学品或卖家的数量或两者都足够小，使得一维上的指数或状态压缩方法变得可行。 此界限强烈表明化学品或卖家子集上的典型密集 DP。 

天真的解释可能会尝试将每种化学品独立分配给最便宜的卖家，但这会失败，因为它忽略了运费。 实际成本与化学品的决策相结合。 

贪心赋值的一个微妙的失败案例：

 假设两种化学品和两个卖家：

 价格：

 化学品 1：卖家 1 = 100，卖家 2 = 1

 化学品 2：卖家 1 = 100，卖家 2 = 1

 运费：卖家1 = 1，卖家2 = 100

 Greedy 为这两种化学品选择了卖家 2，因为 1 < 100 单独支付，支付 1 + 1 + 100 = 102 一次交货。 但对于这两种化学品来说，最优的是卖方 1：100 + 100 + 1 = 201，因此在这种情况下，贪婪似乎更好，但翻转数字会稍微显示出问题：正确的结构取决于分组，而不是每个项目的最小值。 

关键问题是卖方的选择对于每种化学品来说并不是独立的，因此我们必须对子集进行推理。 

## 方法

 如果我们忽略运费，每种化学品都会独立选择最便宜的卖家，而答案只是按列排列的最小值。 困难在于，选择卖家一旦以固定成本“解锁”多种化学品，就会产生分组问题。 

一种强力方法是将每种化学品分配给其中一个销售商，计算包括激活费在内的成本，并取最小值。 这会导致 c^r 分配，即使对于中等 r 也是不可能的。 

关键的结构观察是 r × c ≤ 250，因此 r 或 c 必须很小。 我们可以选择较小的维度作为“状态维度”，并将跨其他维度的分配视为转换。 当 r 很小时，这自然会导致对化学品子集的位掩码动态编程，或者等效地当 c 很小时对卖家子集的位掩码动态编程。 

我们将这个问题重新解释为化学品的覆盖范围。 每个卖家代表一个“包”，可以涵盖任何化学品子集，其中子集的成本是所选每种化学品价格加上一笔激活费的总和。 然后我们希望使用分区将所有化学品覆盖到此类包装中，从而最大限度地降低成本。 

这是一个经典的子集 DP：对于每个卖家，我们计算仅使用该卖家提供任何化学品子集的最佳成本，然后通过化学品子集上的 DP 合并卖家。 

子集上的过渡类似于背包：我们迭代地将每个卖家的贡献与现有的 DP 状态合并，在子集的并集上取最小值。 

这将问题从两个维度的指数减少为仅在 r 或 c（以较小者为准）上的指数。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力作业 | O(c^r) | O(c^r) | O(1) | O(1) | 太慢了|
 | 较小维度上的子集 DP | O(min(r,c) · 2^min(r,c)) | O(min(r,c) · 2^min(r,c)) | O(2^min(r,c)) | O(2^min(r,c)) | 已接受 |

 ## 算法演练

 如果需要的话，我们假设转置矩阵后 r ≤ c，因此 r 是用于位掩码的化学物质的数量。 

## 步骤 1：标准化维度

 如果 r > c，我们转置矩阵，使 r 成为较小的维度。 这可确保子集 DP 总共运行在最多 250 个元素上，从而保持 2^r 可管理。 

这一步很重要的原因是指数复杂度取决于我们选择状态压缩的维度。 

## 步骤 2：预先计算卖家子集成本

 对于每个卖家 j，我们计算一个成本数组，其中对于化学品的每个子集掩码，我们评估从卖家 j 购买这些化学品的成本。 

我们将此成本定义为子集中包含的所有 i 的 ai,j 之和，如果子集非空，则加上 dj。 

此步骤将每个卖家转换为子集上的函数，这至关重要，因为它让我们将每个卖家视为“捆绑包提供商”。 

## 第三步：初始化DP

 我们将 dp[mask] 定义为使用迄今为止处理的某些卖家子集精确覆盖 mask 所代表的一组化学品的最低成本。 

我们将 dp[0] = 0 和所有其他状态初始化为无穷大。 

这反映出“不覆盖任何东西”是不需要任何成本的。 

## 步骤 4：迭代卖家并合并状态

 对于每个卖家 j，我们考虑使用该卖家的子集成本来更新 dp。 

我们尝试代表从卖家 j 购买的化学品的所有子集 mask1 以及所有现有的 dp 状态 mask2，并将它们组合成 mask2 | 掩码1。 

我们更新 dp[mask2 | mask1] 和 dp[mask2] + cost_j[mask1]。 

此步骤强制每个卖家要么未使用，要么使用一次，并在其子集成本定义中隐式支付其激活成本。 

我们以这种方式合并的原因是每个卖家独立贡献一个“子集选择”，最终的解决方案是在卖家之间划分化学品。 

## 步骤5：答案提取

 处理完所有卖家后，dp[(1 << r) - 1] 给出涵盖所有化学品的最低成本。 

此状态表示每种化学品已分配给至少一个卖家。 

## 为什么它有效

 保持的不变性是，在处理前 k 个卖家之后，dp[mask] 存储仅使用这 k 个卖家精确覆盖设置掩码的最小成本。 每次转换都对应于为当前卖家选择化学品的子集并将其与之前可实现的配置合并。 

因为每个化学分配都唯一地归因于 DP 结构中的一个卖方，并且每个卖方选择都在子集中详尽枚举，所以不会遗漏任何有效配置。 DP 探索了跨卖家的化学品集的所有分区，这与有效解决方案的结构完全匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve_case(r, c, A, d):
    # ensure r is small
    if r > c:
        # transpose
        A = [list(x) for x in zip(*A)]
        r, c = c, r
        # d remains same length c after swap logic; but roles swapped:
        # now we treat original sellers as chemicals, so adjust
        # we instead rebuild d as per new columns
        # original d was per seller; after transpose, rows are sellers
        # so d becomes per row -> new "seller costs"
        # but conceptually unchanged: each column is a "seller"
        d = d  # no change needed structurally in DP formulation below

    # precompute subset costs for each seller
    subset_cost = [[0] * (1 << r) for _ in range(c)]

    for j in range(c):
        for mask in range(1 << r):
            s = 0
            for i in range(r):
                if mask & (1 << i):
                    s += A[i][j]
            if mask:
                subset_cost[j][mask] = s + d[j]
            else:
                subset_cost[j][mask] = 0

    dp = [INF] * (1 << r)
    dp[0] = 0

    for j in range(c):
        ndp = dp[:]
        for mask2 in range(1 << r):
            if dp[mask2] == INF:
                continue
            for mask1 in range(1 << r):
                cost = subset_cost[j][mask1]
                if cost == 0:
                    continue
                nm = mask2 | mask1
                ndp[nm] = min(ndp[nm], dp[mask2] + cost)
        dp = ndp

    return dp[(1 << r) - 1]

def main():
    T = int(input())
    out = []
    for _ in range(T):
        r, c = map(int, input().split())
        A = [list(map(int, input().split())) for _ in range(r)]
        d = list(map(int, input().split()))
        out.append(str(solve_case(r, c, A, d)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```实现直接遵循子集 DP 解释。 主要的技术选择是将每个卖家表示为完整的子集成本生成器，然后通过位掩码或转换进行合并。 

一个微妙的点是跳过空的子集，因为从卖家处选择任何内容都不会触发运费。 这就是为什么 mask = 0 在转换过程中被排除。 

另一个重要的细节是将每个卖家的 dp 复制到 ndp 中。 这可以防止在同一迭代中多次重复使用同一卖家，从而保留“每个卖家最多使用一次”的结构。 

## 工作示例

 考虑一个简化案例，其中 r = 3 种化学品和 2 名卖家。 

卖家价格和费用：

 卖家 1：[1, 10, 100]，费用 = 5

 卖家 2：[10, 1, 1]，费用 = 3

 我们计算卖家 1 的子集成本：

 | 面膜| 化学品 | 成本|
 | ---| ---| ---|
 | 001| {1} | 1 + 5 = 6 |
 | 010| {2} | 10 + 5 = 15 | 10 + 5 = 15 |
 | 100 | 100 {3} | 100 + 5 = 105 | 100 + 5 = 105 |
 | 011| {1,2} | 11 + 5 = 16 | 11 + 5 = 16
 | 111 | 111 {1,2,3} | 111 + 5 = 116 |

 对于卖家 2：

 | 面膜| 化学品 | 成本|
 | ---| ---| ---|
 | 001| {1} | 10 + 3 = 13 | 10 + 3 = 13 |
 | 010| {2} | 1 + 3 = 4 |
 | 100 | 100 {3} | 1 + 3 = 4 |
 | 011| {2,3} | 2 + 3 = 5 | 2 + 3 = 5
 | 111 | 111 {1,2,3} | 12 + 3 = 15 |

 DP 从 dp[0] = 0 开始。 

在处理卖方 1 后，dp 反映了仅使用卖方 1 即可实现的所有子集。在卖方 2 之后，我们将先前的状态与新的子集结合起来以形成更好的覆盖范围。 

最终的 dp[111] 根据最佳分配，选择销售者 2 购买更便宜的化学品，并可能选择销售者 1 购买昂贵的第一种化学品。 

该跟踪显示了子集合并如何自然地编码不同卖家之间的化学品分裂。

 ## 边缘情况

 一个关键的边缘情况是，尽管单个卖家的价格很高，但只使用一个卖家是最佳的，因为分散在多个卖家之间会支付多笔运费。 DP 通过允许直接从一个卖家处获取全套掩码作为有效的子集选择来处理此问题。 

另一个边缘情况是最佳解决方案将每种化学品分配给不同的卖家。 在这种情况下，DP会从不同的卖家中选择单一的口罩并逐步合并。 基于 OR 的组合可确保状态表示中不会丢失或重复化学物质。 

最后，当一个卖家的运费极高但商品价格较低的情况下，可以正确处理，因为子集成本始终仅在子集非空时才包含费用，这使得大量捆绑选择自然比分散选择更具竞争力。
