 ## 解决方案
 ## 问题理解

 我们有两个非常大的方阵$A$和$B$，但并未完整提供。 相反，每个矩阵仅由其非零条目描述。 每个缺失位置隐式为零，并且非零条目的数量与$n^2$。 

任务是计算产品的迹$AB$。 具体来说，如果$C = AB$，我们需要所有对角线条目的总和$C_{i,i}$，以固定大素数为模进行计算。 

直接扩展定义，每个对角线元素$C$是$$C_{i,i} = \sum_{k=1}^{n} A_{i,k} B_{k,i}$$所以痕迹变成$$\mathrm{tr}(AB) = \sum_{i=1}^{n} \sum_{k=1}^{n} A_{i,k} B_{k,i}.$$输入大小清楚地表明$n$可以大到$10^5$，而非零条目的数量仅与$n$。 这立即排除了任何迭代所有方法$n^2$矩阵位置或执行标准矩阵乘法。 甚至$O(nk)$或者$O(k^2)$和$k \approx 1.5n$仅当避免依赖时才是可接受的$n$本身。 

关键的结构约束是稀疏性：每个操作都必须根据非零条目的数量而不是矩阵维度进行缩放。 

当我们假设我们必须显式构建乘积矩阵时，就会出现一种微妙的故障模式。 这是不可能的，因为即使是单行$A$可能与许多条目交互$B$，反之亦然，如果处理不当，会创建太多中间组合。 

另一个微妙的问题是重复计算风险。 如果循环遍历以下条目$A$并且对于每个尝试匹配的所有条目$B$，很容易意外地累积两个方向的贡献或错过索引对齐。 贡献仅存在于$A_{i,k}$和$B_{k,i}$共享相同的中间索引$k$，如果数据没有预先分组，很容易误处理。 

## 方法

 直接解释将跟踪公式扩展为三重嵌套循环。 对于每对$(i,k)$在$A$，我们搜索行中的所有条目$k$的$B$查找列$i$。 在最坏的情况下，这会退化为扫描所有非零条目$B$对于每个条目$A$, 给予$O(k_a k_b)$，这大约是$O(n^2)$。 这太慢了$n$是$10^5$。 

关键的观察结果是表达式$$\sum_{i,k} A_{i,k} B_{k,i}$$仅取决于共享相同中间索引的条目对$k$。 我们可以不考虑矩阵乘法，而是将其重新解释为匹配问题：对于每个固定的$k$，我们希望所有值对都来自行$k$在$A$和列$k$在$B$。 

这建议重新组织数据。 如果我们将条目分组$A$通过它们的行索引和条目$B$通过它们的列索引，然后对于每个共享索引$k, i$我们可以直接将匹配值相乘。 这将问题简化为仅迭代实际的非零条目并在哈希映射中累积贡献。 

每个非零条目$A$在$(i,k)$贡献条目$B$那正是$(k,i)$，所以我们可以索引$B$适当地按行或列并在线性时间内匹配。 

因此，问题简化为存储稀疏邻接列表并有效地求和匹配的乘积。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(k_a k_b)$|$O(k_a + k_b)$| 太慢了|
 | 稀疏哈希匹配|$O(k_a + k_b)$|$O(k_a + k_b)$| 已接受 |

 ## 算法演练

 我们想要计算$\sum_{i,k} A_{i,k} B_{k,i}$无需显式迭代所有对。 

1. 读取所有非零条目$A$并将它们存储在以行索引为键的字典中。 对于每一行$i$，我们维护一个对的列表$(k, A_{i,k})$。 这种结构使我们能够有效地访问来自固定行的所有传出连接。 
2. 读取所有非零条目$B$并将它们存储在以行索引为键的字典中，但仔细解释为$B_{k,i}$。 对于每一行$k$，我们维护一个对的列表$(i, B_{k,i})$。 这会对齐共享索引$k$跨两个矩阵。 
3. 初始化一个累加器，将答案以给定模数为模。 
4. 迭代每行索引$k$出现在$B$。 对于每个条目$(i, B_{k,i})$在该行中，我们查找行$i$在$A$。 该行中的每个条目$A$， 说$(k', A_{i,k'})$，仅当$k' = k$。 所以我们必须匹配第二个坐标。 

为了避免扫描不相关的条目，我们改为预索引$A$也按列，为每列存储$k$所有对$(i, A_{i,k})$。 
5. 现在对于每个$k$，我们有两个列表：全部$A$- 带栏的条目$k$，以及所有$B$- 带有行的条目$k$。 我们将这两个列表中的每一对相乘，匹配共享结构$A_{i,k}$和$B_{k,i}$。 
6. 积累$A_{i,k} \cdot B_{k,i}$将答案以所需的模数为模。 
7. 输出最终累加值。 

### 为什么它有效

 跟踪的表达式精确地隔离了那些索引对，其中列索引为$A$匹配行索引$B$，其中行索引$A$匹配列索引$B$。 通过按共享中间索引对条目进行分组$k$，我们确保每一个有效的产品$A_{i,k} B_{k,i}$只计算一次。 不可能有其他组合，因为不匹配的索引永远不会满足跟踪约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1006903069

def main():
    n = int(input())
    
    ka = int(input())
    A_by_col = {}
    
    for _ in range(ka):
        i, j, x = map(int, input().split())
        if j not in A_by_col:
            A_by_col[j] = []
        A_by_col[j].append((i, x))
    
    kb = int(input())
    B_by_row = {}
    
    for _ in range(kb):
        i, j, x = map(int, input().split())
        if i not in B_by_row:
            B_by_row[i] = []
        B_by_row[i].append((j, x))
    
    ans = 0
    
    for k in B_by_row:
        if k not in A_by_col:
            continue
        A_list = A_by_col[k]
        B_list = B_by_row[k]
        
        for i, bval in B_list:
            for i2, aval in A_list:
                if i2 == i:
                    ans = (ans + aval * bval) % MOD
    
    print(ans)

if __name__ == "__main__":
    main()
```实施商店$A$按列分组，以便列索引$k$成为集合点。 对于每个$k$，我们检索所有$A_{i,k}$和所有$B_{k,i}$，并且仅当行索引位于$A$匹配列索引$B$。 嵌套循环是安全的，因为每个列表都受到稀疏约束的限制，并且存储条目的总数与$n$。 

关键的微妙之处是确保索引的正确对齐。 一个常见的错误是按行对两个矩阵进行分组，这会丢失跟踪表达式所需的交叉匹配结构。

 | 测量 | 复杂性 | 说明|

## 测试用例```python
import sys, io

MOD = 1006903069

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    ka = int(input())
    A = {}
    for _ in range(ka):
        i, j, x = map(int, input().split())
        A.setdefault(j, []).append((i, x))

    kb = int(input())
    B = {}
    for _ in range(kb):
        i, j, x = map(int, input().split())
        B.setdefault(i, []).append((j, x))

    ans = 0
    for k in A:
        if k not in B:
            continue
        for i, ax in A[k]:
            for j, bx in B[k]:
                if i == j:
                    ans = (ans + ax * bx) % MOD

    return str(ans)

 ## 边缘情况

 一个重要的边缘情况是当一个值出现在$A$但其匹配索引不存在于$B$。 例如，如果$A$包含$(2,5)=10$但$B$没有包含行的条目$5$，那么这个贡献必定消失。 在算法中，这是自然处理的，因为我们只迭代两个字典中存在的键，因此丢失的行不会产生迭代，也不会产生意外贡献。 

另一个边缘情况是多个条目共享相同的中间索引。 认为$A$列中有两个条目$k$， 和$B$行中有两个条目$k$。 该算法在该组内形成完整的叉积，但只有索引匹配的那些对才会起作用。 这是通过嵌套循环内的相等检查来处理的，确保不会计算错误的对。
