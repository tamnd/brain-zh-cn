 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 In each scenario, there are$n$村民，每个村民都以一个非负整数值开始，称为脾气暴躁。 改变这种情况的唯一方法是反复挑选两个村民并进行互动，这样既可以减少他们的脾气，也有可能在他们之间建立友谊。 

村民之间的每一次互动$i$和$j$行为如下：我们支付的祖母绿数量等于$\max(g_i, g_j)$。 然后两个村民的脾气都减少了$\min(g_i, g_j)$。 结果，至少其中一个变为零，因为较小的值被完全减去。 该操作还使用无向边将它们连接起来。 

目标不是直接最小化脾气暴躁或最大化友谊，而是确保经过一些操作序列后，友谊图变得连通。 换句话说，每个村民都必须能够通过创造边缘的一系列操作联系到其他村民。 

关键输出是保证这种连接所花费的最小祖母绿总数。 

约束条件很大：最多$2 \cdot 10^5$测试用例中的村民总数。 这立即排除了任何尝试所有对或模拟密集图构造的方法。 每个测试用例的解决方案最多必须是线性或接近线性的，通常$O(n \log n)$或者$O(n)$。 

当贪婪地考虑仅连接相邻或较小的值时，会出现微妙的失败情况。 例如，考虑$g = [1, 100, 100]$。 一个天真的想法可能会尝试首先连接最小的，但成本结构取决于最大和最小的交互，因此配对选择可以极大地改变总成本。 另一个陷阱是假设我们只需要$n-1$最便宜的直达航班； 这些操作动态地减少值，因此边缘不是独立的。 

## 方法

 暴力的观点是考虑在村民上构建一棵生成树，其中每条边都有因在两个节点之间执行操作而产生的成本。 对于每个潜在边$(i, j)$，我们可以计算执行该操作的成本，然后运行最小生成树算法。 然而，困难在于边权重不是固定的。 成本取决于当前的脾气暴躁值，并且这些值在操作后会发生变化，因此“边缘权重”不是静态的。 对操作序列的简单模拟会导致指数分支过程，因为每个操作都会改变状态空间。 

关键的见解是观察到，每项操作都有效地将较小的脾气转变为连通性，而较小的脾气每减少一单位，只需支付一次较大的价值。 每个村民的脾气都可以被解释为一种资源，必须被“吸收”到某种结构中。 事实证明，最佳结构相当于选择一个单一的“类根”策略，在该策略中组织减少，以便每个脾气暴躁单位都只支付一次，除了取决于最小元素的全局校正之外。 

更具体地说，可以通过注意到除了一个村民之外的每个村民最终都必须通过互动而减少到零，从而得出最佳策略，每次减少每减少一个单位，至少对他们的当前价值收取一次。 这导致了一个公式，其中总成本是所有脾气暴躁值加上避免重复计算最小元素的调整的总和。 

这将问题从动态对运算简化为数组上的简单算术表达式。

 ## 算法演练

 1. 计算所有脾气暴躁值的总和。 这代表了一个基线，假设每个脾气暴躁单位都会独立地增加成本。 运营结构确保每个单位必须至少“付款”一次。 
2. 找出数组中脾气暴躁程度最小的值。 该元素起着特殊的作用，因为它可以以避免在最佳结构中过度计算成本的方式进行配对。 
3. 从总和中减去该最小值，但不要减去两次或多次。 原因是最小的元素可以通过避免多余的昂贵相互作用的方式被完全吸收。 
4. 输出调整后的总和作为测试用例的答案。 

### 为什么它有效

 这个过程可以理解为构建一个连接的结构，其中每个村民最终通过操作合并成一个连接的组件，这些操作总是消除一对中较小的脾气暴躁的人。 每个脾气暴躁单位都必须参与至少一个减少步骤，至少为总成本贡献其价值。 然而，最小的脾气总是可以被安排为最终的吸收枢轴，因此它的贡献不需要通过中间昂贵的配对来“复制”。 这恰好创建了一个等于最小元素的全局节省，从而给出了最优成本公式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total = sum(a)
        mn = min(a)
        print(total - mn)

if __name__ == "__main__":
    solve()
```实施是直接的。 该解决方案读取每个测试用例，计算数组的总和和最小值，并输出它们的差值。 

关键细节是这两项操作都是针对每个测试用例独立完成的。 使用Python的内置`sum`和`min`保持实现线性并避免任何排序或配对模拟的需要。 

除了确保正确读取输入行之外，不需要边缘情况处理，因为所有值都是正数并且数组始终非空。

 ## 边缘情况

 一个微妙的情况是所有值都相同，例如$g = [5, 5, 5]$。 该算法计算$15 - 5 = 10$。 正确性来自于任何元素都可以作为“吸收”最小值，并且对称性确保不需要特殊的结构。 

另一种情况是最小值出现多次，例如$g = [1, 1, 10]$。 该算法仅减去最小值的一个副本，给出$12 - 1 = 11$。 在操作期间，无论存在多少个最小元素，都只能实现一个单位的全局节省，因为连接性要求迫使至少其中一个元素用于全成本交互。 

对于极端的差异，例如$g = [1, 10^9]$，答案就变成了$10^9$。 小元件仅起到一次性吸收器的作用，而大元件则在成本上占主导地位。
