 ## 问题理解

 我们得到一个仅包含以下内容的二进制字符串`0`和`1`。 我们关心的值是该字符串中的反转次数，其中反转是一对位置`i < j`使得一个`1`出现在 a 之前`0`。 换句话说，每次`1`位于 a 的左侧`0`，这为成本贡献了一个单位。 

您最多可以执行一项操作：选择两个相邻的字符并交换它们。 您也可以选择什么都不做。 在这个可选的单次交换之后，目标是最小化反转总数。 

问题是输入大小很小，但结构很微妙，因为单个相邻交换不仅可以在本地更改反转计数，还可以通过与交换对两侧的所有字符交互来更改反转计数。 

这里的自然限制是字符串长度很小（最多 100）。 这立即排除了任何比每个测试用例的大致二次推理更复杂的事情。 在尝试所有可能的交换后从头开始重新计算反转计数的解决方案在复杂性方面已经可以接受，但关键的困难在于干净地完成它并且不要错过交换下反转计数的变化。 

一些边缘情况比它们最初出现时更重要。 一个没有的字符串`10`图案如`0000`或者`1111`行为很简单，因为交换相邻的相同字符不会改变任何内容。 像这样的字符串`1000`更有趣的是，交换前两个字符可以同时减少多个反转。 另一种棘手的情况是当最佳交换不是立即减少局部反转的交换时，例如`1010`，如果不计算完整效果，最佳交换并不明显。 

## 方法

 暴力破解的想法很简单：尝试每一个可能的相邻交换，计算结果字符串的反转计数，并取最小值。 最多有`n - 1`交换，并且每个反转计算都可以在`O(n)`通过扫描并计算有多少`1`到目前为止已经看到了多少个`0`我们追赶他们。 这给出了`O(n^2)`每个测试用例，这已经足够了`n ≤ 100`。 

关键的观察是，我们实际上不需要以优化的方式从头开始重新计算所有内容，因为约束很小。 然而，理解交换改变反转的原因仍然很重要：交换两个相邻字符只会影响涉及交换索引周围位置的对。 遥远的一切都保持不变。 这意味着即使完整的重新计算更简单、更安全，反转计数的差异也可以在本地推理。 

因此，最佳方法本质上是具有正确反转计数器的受控蛮力。 真正的洞察力不是算法简化，而是认识到问题的规模允许直接评估所有状态。

 | 优化每次交换的增量更新 | O(n²) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们修正了这样的想法：我们将评估原始字符串以及由恰好一个相邻交换形成的每个字符串。 

1. 计算原始字符串的反转次数。 我们通过从左到右扫描并维护有多少个来做到这一点`1`已经被看到了。 每次我们看到一个`0`，它贡献与数量一样多的反转`1`已经看过了。 
2. 使用该原始反转计数初始化答案，因为不允许执行任何操作。 
3. 对于每个索引`i`从`0`到`n - 2`，模拟交换`s[i]`和`s[i + 1]`。 这将创建一个仅在这两个位置不同的候选字符串。 
4. 对于每个这样的交换字符串，使用与步骤 1 相同的扫描方法重新计算其反转计数。 
5. 保留所有候选值中的最小值。 

我们明确地重新计算而不是尝试调整之前的答案的原因是字符串足够小，因此清晰度比微优化更有价值。 掉期影响所有涉及头寸的反转`i`和`i + 1`，并且正确跟踪所有这些贡献在复杂性上相当于重新计算。 

### 为什么它有效

 允许的操作可到达的每个有效状态要么是原始字符串，要么是通过交换单个相邻对形成的字符串之一。 该算法详尽地评估所有此类状态。 由于反转函数是针对每个状态完全重新计算的，因此不会错过交换之间的交互。 因此，这个有限集合的最小值是真正的最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def inversion_count(s):
    ones = 0
    inv = 0
    for ch in s:
        if ch == '1':
            ones += 1
        else:
            inv += ones
    return inv

def solve():
    s = list(input().strip())
    n = len(s)

    best = inversion_count(s)

    for i in range(n - 1):
        s[i], s[i + 1] = s[i + 1], s[i]
        best = min(best, inversion_count(s))
        s[i], s[i + 1] = s[i + 1], s[i]

    print(best)

if __name__ == "__main__":
    solve()
```该解决方案将反转计数分离到辅助函数中，以便可以一致地评估每个候选状态。 交换循环会在每次尝试交换后小心地恢复字符串，从而避免意外的状态损坏。 

一个微妙的点是，我们从不尝试增量地维护跨交换的反转计数。 虽然这是可能的，但它引入了许多关于涉及交换位置的反转如何变化的极端情况。 重新计算避免了所有这些陷阱，而对于这一约束的成本可以忽略不计。

 ## 边缘情况

 所有相同字符组成的字符串的行为很平常，因为无法创建或删除反转。 该算法仍然评估交换，但每次交换产生相同的反转计数，因此最小值保持不变。 

像这样的字符串`1000`展示了单次交换的最强效果。 最初有三个反转。 交换前两个字符会产生`0100`，这消除了所有反转，因为没有`1`在一个之前`0`之后。 该算法正确地捕获了这一点，因为它重新计算每个交换状态的反转计数，而不是仅假设本地更改。 

像这样的字符串`0101`暴露出交换并不总是有帮助。 某些交换会增加反转，并且算法会安全地忽略它们，因为它始终与原始配置进行比较并保持所有候选配置中的最小值。
