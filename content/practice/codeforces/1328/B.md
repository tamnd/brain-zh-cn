 ## 解决方案

 ## 问题理解

 我们正在查看所有长度的二进制字符串`n`恰好包含该字母的两次出现`b`，而其他所有位置都充满了`a`。 由于字母表的顺序是`a < b`, 以更多前导开头的字符串`a`s 按字典顺序排在前面，并放置`b`较早推入字符串。 

The task is to imagine all such strings sorted like words in a dictionary and return the one at position`k`。 

输入给出多个查询。 每个查询提供一个长度`n`和一个等级`k`，并且我们必须直接构造第 k 个字符串，而不生成所有候选字符串。 

这些约束迫使我们每次测试的复杂度为 O(n) 或总体上更好的解决方案。 由于所有的总和`n`取决于`10^5`，任何二次方`n`或枚举所有对`b`每个测试用例的位置是不可行的。 

天真的尝试会生成所有位置对`(i, j)`和`i < j`，构建字符串，并对它们进行排序。 这已经产生了`O(n^2)`每个测试用例的字符串，甚至显式构建它们都会导致 TLE。 

一个更微妙的失败案例来自于在不了解组合结构的情况下试图贪婪地模拟字典排序。 例如，错误地假设第一个`b`位置独立于第二个确定会导致错误的排名，因为完成的数量取决于两个选择。 

## 方法

 蛮力视图很简单：选择两个索引`b`字符，构建字符串并对所有结果进行排序。 这在概念上是有效的，因为每个有效字符串都唯一对应于一对`(i, j)`和`i < j`。 然而，这样的对的数量是`n(n-1)/2`，因此即使列出它们也会变得二次，并且对它们进行排序会在重字符串结构之上添加另一个对数因子。 

关键的观察是字典顺序与第一个位置完美对齐`b`。 如果我们修复第一个`b`在位置`i`，然后是第二个`b`可以严格放置在之后的任何地方`i`。 所有此类字符串按字典顺序形成一个连续的块。 

对于固定的`i`，第二个的选择数`b`是`n - i`。 这意味着位置的块大小`i`是`n - i`。 我们可以按照递增的顺序扫描这些块`i`并从中减去块大小`k`直到我们找到正确的第一个`b`位置。 之后，剩余的偏移量直接告诉我们第二个在哪里`b`去。 

这将问题减少到每个测试用例一次线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n² log n) | O(n² log n) | O(n²) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将每个有效字符串视为由两个索引确定`i < j`其中两个位置都包含`b`。 

1.我们迭代`i`从 1 到`n-1`, 治疗`i`作为第一个的位置`b`。 
2. 对于每个`i`，我们计算有多少个字符串以`b`在`i`。 这等于`n - i`因为第二个`b`之后可以在任何位置`i`。 
3.如果`k`大于这个块大小，我们减去它并移动到下一个`i`。 这意味着第 k 个字符串不在该块中。 
4.一旦我们找到一个`i`这样`k <= n - i`，我们修复第一个`b`在`i`。 
5.第二个`b`然后处于位置`i + k`。 这是有效的，因为在这个块中，字典顺序完全对应于第二个的递增位置`b`。 
6. 我们构造最终的字符串`a`到处
