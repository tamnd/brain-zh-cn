 ## 解决方案
 ## 问题理解

 每个测试用例包含两个正整数。 我们可能只执行一种操作：将第一个数字加一。 目标是达到大于或等于当前可被第二个数字整除的最接近值，同时使用尽可能少的增量。 

输入从测试用例的数量开始，然后独立处理每对数字。 对于每一对，我们必须输出第一个数字成为第二个数字的倍数之前需要多少增量。 

测试用例数量达到$10^4$，而两个数字都可以大到$10^9$。 这些限制对于每个测试用例的恒定时间工作来说足够小，但它们排除了任何重复加一直到实现整除的方法。 在最坏的情况下，答案本身可能是巨大的，因此模拟可能需要数亿甚至数十亿次迭代。 

一些边缘情况值得关注。 

当第一个数字可以被第二个数字整除时，答案为零。 

输入：```
1
92 46
```输出：```
0
```一个粗心的公式，例如`b - (a % b)`产生`46`，这是不正确的，因为不需要移动。 

当除数大于当前值时，会出现另一种棘手的情况。 

输入：```
1
123 456
```输出：```
333
```456 的下一个倍数是 456 本身，所以我们需要$456-123=333$增量。 

一个非常小的例子也可能暴露出相差一的错误。 

输入：```
1
10 4
```输出：```
2
```自从$10 \bmod 4 = 2$，还需要两个增量才能达到 12。使用不正确的表达式，例如`b - a % b - 1`会给出 1 而不是 2。 

## 方法

 最直接的策略是反复将数字加一，并在能被除数整除时立即停止。 这种方法是正确的，因为每个操作都是强制的，并且在第一个可整除值处停止给出了最小的移动次数。 

这种方法的问题是它的运行时间。 认为$a=1$和$b=10^9$。 我们会表演$999\,999\,999$在达到第一个倍数之前递增$10^9$。 这样的模拟速度太慢了。 

关键的观察是整除性仅取决于除以时的余数$b$。 如果余数是$r$，那么正好$b-r$需要更多单位才能达到下一个倍数。 唯一的例外发生在$r=0$，因为数字已经可以整除，不需要进行任何操作。 

蛮力之所以有效，是因为它最终达到了下一个倍数，但当差距很大时就会失败。 余数已经告诉我们距离该倍数有多远，这一观察将问题简化为一些算术运算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O（答案）| O(1) | O(1) | 太慢了|
 | 最佳 | 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取测试用例的数量并独立处理每一对，因为用例不会交互。 
2. 计算余数`a % b`。 这告诉我们当前值与最接近的较小倍数的距离有多远`b`。 
3. 如果余数为零，则输出零，因为当前值已可整除。 
4.否则，输出`b - remainder`。 这个数量正是从当前值到下一个倍数的距离`b`。 

### 为什么它有效

 对于任意整数$a$，我们可以写$$a = kb + r,$$在哪里$0 \le r < b$。 如果$r=0$， 然后$a$本身是一个倍数$b$。 否则，下一个倍数是$$(k+1)b = kb + b.$$这两个值之间的差异是$$(k+1)b-a = b-r.$$不能使用更小的增量，因为每个中间值仍然具有非零余数。 因此，该算法总是产生最少的移动次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    a, b = map(int, input().split())
    rem = a % b

    if rem == 0:
        print(0)
    else:
        print(b - rem)
```该程序首先读取测试用例的数量并分别处理每一对。 

对于每一对，它计算除法后的余数`a`经过`b`。 这个余数决定了这个数字与前一个倍数的差距。 如果余数为零，则答案立即为零。 

否则，到下一个倍数的距离等于`b - rem`。 

唯一微妙的一点是可分割的情况。 只写`b - (a % b)`给出错误答案时`a % b`为零，因为它会输出`b`而不是`0`。 单独处理这种情况可以避免差一错误。

 ## 边缘情况

 考虑数字已经可整除的情况。 

输入：```
1
92 46
```该算法计算`92 % 46 = 0`。 由于余数为零，因此立即输出 0。不需要增量，并且特殊情况可以防止错误返回 46。 

现在考虑一个大于当前值的除数。 

输入：```
1
123 456
```余数等于 123。算法计算`456 - 123 = 333`，这意味着 123 正好增加 333 次，达到 456。任何较小的增量都会产生低于 456 的值，并且不能被 456 整除。 

最后，考虑一个可以暴露相差一错误的情况。 

输入：```
1
10 4
```余数为 2。算法返回`4 - 2 = 2`，意味着数列变为11，然后变为12。经过两次运算，就实现了整除。 一次运算是不够的，因为 11 不能被 4 整除。
