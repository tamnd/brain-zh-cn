 ## 解决方案
 ## 问题理解

 我们有一个圆形的位置排列，每个位置都有一种动物类型。 这些位置循环连接，因此在最后一个位置之后又出现第一个位置。 我们必须为每个位置分配一种颜色。 

约束是局部的：每当循环上的两个相邻位置具有不同的动物类型时，它们就不允许共享相同的颜色。 如果两个相邻位置具有相同的类型，则它们可以共享颜色而不会违反任何规定。 目标是最大限度地减少总体使用的不同颜色的数量，同时遵守此邻接规则。 

这可以被视为对循环图进行着色，其中边缘仅在具有不同值的位置之间“重要”。 相等的相邻值有效地打破了该边缘的约束。 

输入规模很大，测试用例中的 n 总数高达 2·10^5。 这排除了每个测试用例的任何二次方。 任何解决方案对于每个测试用例都必须基本上是线性的，因为即使重复多次 O(n log n) 在最坏情况下也会很紧。 

一个关键的微妙之处是位置 n 和位置 1 之间的圆形边缘。许多不正确的贪婪方法仅在这种环绕约束上失败。 例如，如果除了最后一个值与第一种类型模式匹配之外所有值都是交替的，则循环闭包可以强制使用额外的颜色或允许根据奇偶性和对称性进行压缩。 

当所有元素都相同时，会出现另一种边缘情况。 在这种情况下，根本没有任何限制，因此单一颜色就足够了。 假设至少有两种颜色用于交替图案的简单解决方案会使这种情况过度着色。 

最后，最微妙的情况是当数组几乎是交替的但恰好包含一个“中断”时或者当循环奇偶校验与端点相等冲突时。 此时答案变为 2 或 3，具体取决于有效边沿下循环是否为二分循环。 

## 方法

 暴力尝试会尝试增量分配颜色，同时在发生冲突时回溯。 在每个位置，我们可以选择任何不违反与其邻居的邻接约束的颜色。 在最坏的情况下，这会变成指数，因为每个位置可能分支为多种颜色选择，并且循环约束将第一个和最后一个位置耦合起来。 

一种更结构化的暴力方法是从 1 向上尝试 k 并测试是否存在有效的着色。 对于每个 k，我们将在具有选择性边的循环图上运行图着色可行性检查。 如果我们测试许多值，在最坏的情况下，这仍然会花费 O(n·k) 或 O(n²)。 

关键的观察结果是约束图非常简单：它是一个循环，只有当相邻类型不同时，边才重要。 这样的图的最大度为 2，因此它的结构是路径的集合加上可能的环。 每个连接的组件要么是一条路径，要么是一个循环。 这立即限制了色数：路径是 2 种颜色的，循环是 2 种颜色的，除非它们是奇数循环。 

因此，答案只能是 1、2 或 3。我们唯一需要 3 种颜色的情况是，至少有一条边，并且所有“主动约束”形成的循环都是奇数长度，从而由于环绕而强制出现奇偶校验矛盾。 

一个建设性的解决方案是将数组视为边缘上的循环着色问题，其中 t[i] ≠ t[i+1]。 然后我们检查是否可以一致地对它进行 2 色着色。 如果没有，我们会在精心选择的断点处引入第三种颜色，以使循环线性化。

 | ---| ---| ---| ---|
 | 蛮力 | O(n·k) 到 O(n²) | O(n) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们根据测试用例进行工作。

1. 首先检查数组中的所有值是否相同。 如果是，则为每个位置分配颜色 1。 不会触发任何邻接约束，因此一种颜色是最佳的。 
2. 否则，我们尝试使用颜色 1 和 2 在循环上构建 2 着色，将每个位置视为一个节点，并强制执行如果 t[i] ≠ t[i+1]，则 c[i] ≠ c[i+1]。 
3. 我们尝试两种可能的起始分配，因为只有在至少一种起始奇偶校验有效的情况下，循环才能保持一致的颜色。 我们在第一次尝试中设置 c[1] = 1。 
4. 我们向前传播：对于从 2 到 n 的每个 i，如果 t[i] 等于 t[i-1]，我们设置 c[i] = c[i-1]，因为它们之间没有约束。 如果它们不同，我们设置 c[i] = 3 - c[i-1]，强制翻转。 
5. 填充完所有颜色后，我们必须验证n和1之间的闭合边缘。如果t[n] ≠ t[1]，我们需要c[n] ≠ c[1]。 如果这个成立，我们接受 2 着色。 
6. 如果验证失败，我们得出结论：2 种颜色是不可能的。 然后，我们通过引入一个断点来构建一个三色解决方案，在该断点处我们故意改变传播。 
7. 要构建 3 色解决方案，请找到索引 i，使得 t[i] ≠ t[i-1]。 像以前一样使用 1 和 2 交替设置 c[1..i]。 然后分配 c[i+1] = 3，并继续用 1 和 2 贪婪地对其余部分进行着色，始终遵守邻接约束。 第三种颜色充当分隔符，打破循环中的奇偶校验冲突。 

### 为什么它有效

 邻接约束定义了一个图，其中边仅存在于不同的连续类型之间。 每个连接的组件要么是一条路径，要么是一个循环。 路径始终是 2 色的。 当且仅当循环的长度是偶数时，它才是 2 色的。 唯一的障碍来自具有由环绕约束引起的奇奇偶校验的单个周期组件。 引入一个颜色为 3 的顶点将该循环分解为一条路径，完全消除奇偶校验约束，之后 2 种颜色足以满足剩余的结构。 这保证了最多 3 种颜色的可行性，并且遵循极简性，因为只有在不存在约束时才可能有 1 种颜色，而当循环条件成立时，恰好有 2 种颜色可能。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        t = list(map(int, input().split()))

        if len(set(t)) == 1:
            print(1)
            print(" ".join(["1"] * n))
            continue

        c = [0] * n

        # try 2-coloring
        c[0] = 1
        for i in range(1, n):
            if t[i] == t[i - 1]:
                c[i] = c[i - 1]
            else:
                c[i] = 3 - c[i - 1]

        ok = True
        if t[0] != t[-1] and c[0] == c[-1]:
            ok = False

        if ok:
            print(2)
            print(" ".join(map(str, c)))
            continue

        # need 3 colors
        c = [0] * n

        # find a differing edge to place the third color
        idx = -1
        for i in range(n):
            if t[i] != t[i - 1]:
                idx = i
                break

        # build from idx
        c[idx] = 3
        for i in range(idx - 1, -1, -1):
            if t[i] == t[i + 1]:
                c[i] = c[i + 1]
            else:
                c[i] = 1 if c[i + 1] == 2 else 2

        for i in range(idx + 1, n):
            if t[i] == t[i - 1]:
                c[i] = c[i - 1]
            else:
                c[i] = 1 if c[i - 1] == 2 else 2

        print(3)
        print(" ".join(map(str, c)))

if __name__ == "__main__":
    solve()
```第一个分支处理根本不存在任何约束的简单情况，允许立即压缩为单一颜色。 第二个分支通过沿相邻类型不同的边缘强制一致性来构建候选 2 着色，有效地将相同的相邻类型视为组件的合并。 

仅圆形闭合需要验证步骤，因为所有内部边缘都通过构造满足。 如果最后一个和第一个不同但接收到相同的颜色，则交替传播会产生不一致的循环，从而强制回退。 

三色结构故意在不同类型之间的过渡点“切断”循环。 选择索引以使切割在约束条件下有效。 从那时起，着色仅使用两种颜色在两个方向上向外进行，因为循环已被分成一条路径。 

## 工作示例

 我们追踪两种情况：一种情况下 2 种颜色就足够了，另一种情况下需要 3 种颜色。 

### 示例 1

 输入：```
5
1 2 1 2 2
```我们从 c[1] = 1 开始。 

| 我| t[i-1], t[i] | t[i-1], t[i] | 规则| c[i] |
 | ---| ---| ---| ---|
 | 1 | - | 开始 | 1 |
 | 2 | 1 ≠ 2 | 翻转| 2 |
 | 3 | 2 ≠ 1 | 2 ≠ 1 翻转| 1 |
 | 4 | 1 ≠ 2 | 翻转| 2 |
 | 5 | 2 = 2 | 复制| 2 |

 现在检查环绕：t[5] = 2，t[1] = 1 不同，但 c[5] = 2，c[1] = 1 不同，因此有效。 

这证实了简单的传播就足够了并且不会出现循环矛盾。 

### 示例 2

 输入：```
5
1 2 1 2 3
```传播：

 | 我| t[i-1], t[i] | t[i-1], t[i] | c[i] |
 | ---| ---| ---|
 | 1 | - | 1 |
 | 2 | 1 ≠ 2 | 2 |
 | 3 | 2 ≠ 1 | 2 ≠ 1 1 |
 | 4 | 1 ≠ 2 | 2 |
 | 5 | 2 ≠ 3 | 2 ≠ 3 1 |

 现在概括一下： t[5] ≠ t[1] 但 c[5] = c[1] = 1，所以冲突。 该循环会产生奇偶校验矛盾，因此我们必须在中断时引入第三种颜色，从而产生有效的三色分配。

 ## 边缘情况

 完全相等的情况会触发没有边的退化图。 该算法立即分配一种颜色，这是最佳的，因为没有任何约束被激活。 任何基于传播的方法仍然有效，但会浪费时间检查不必要的转换。 

当数组完美交替时，会出现第二种边缘情况。 传播会一致地交替颜色，如果奇偶校验匹配，则环绕检查成功。 这证实了具有均匀有效长度的循环仍然是 2-可着色的。 

当原本均匀的数组中恰好存在一个不匹配时，就会出现第三种边缘情况。 传播变得局部一致，但循环闭包引入了矛盾，迫使算法采用 3 色构造。 插入的第三种颜色打破了循环，将其变成一条路径并恢复了可行性，而没有进一步的复杂性。
