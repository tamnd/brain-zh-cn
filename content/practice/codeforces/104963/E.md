 ## 解决方案
 ## 问题理解

 我们在三种操作下维护一个大非负整数的多重集，并且在每次操作之后我们必须报告所有当前元素的按位异或。 

这些操作以两种不同的方式是动态的。 一个操作将每个现有值向上移动一位，另一个操作插入一个新值，最后一个操作删除单个出现的给定值（如果存在）。 每次修改后，我们需要对整个多重集进行异或。 

这些约束立即迫使我们放弃从头开始重新计算异或。 元素和操作的数量都可以达到 200,000，因此任何每次查询扫描整个结构的方法都需要大约$q \cdot n$，这远远超出了可行的限度。 

微妙的难点在于全局增量操作。 每个元素加 1 并不是简单的 XOR 更新，因为 XOR 在加法下不是不变的。 像“只维护全局异或移位”这样的幼稚想法并不能直接起作用，因为进位根据每个元素的位传播不同。 

一个小例子已经说明了为什么天真的思考会失败。 假设我们有元素$[1, 2]$。 他们的异或是$3$。 增加所有元素后我们得到$[2, 3]$，其异或为$1$。 不存在简单的固定变换$3$到$1$这仅取决于计数； 这取决于位结构。 

因此，挑战是支持：

 变化的多重集的异或、插入和删除，以及应用于所有元素的全局+1，所有这些都受到严格的约束。 

打破朴素方法的边缘情况包括重复应用增量操作、删除当前隐式移位的值以及正确处理重复项，因为 XOR 取消了对，但删除必须精确影响重数。 

## 方法

 强力解决方案实际上会将所有元素存储在列表或多集结构中。 对于增量类型的每个查询，我们将为每个元素添加一个。 对于插入和删除，我们将修改容器，并在每次操作后通过迭代所有元素来重新计算 XOR。 

这是正确的，但太慢了。 每次增量成本$O(n)$，并且可以有$q$此类操作，导致$O(nq)$达到$4 \cdot 10^{10}$最坏情况下的操作。 

关键的观察结果是，异或在按位运算上是线性的，但增量运算以结构化方式与位交互。 我们不跟踪实际值，而是跟踪移动坐标系中的值。 

让一个全局变量$add$表示我们对所有元素应用“+1”的次数。 而不是存储实际值$x$，我们存储标准化值$x - add$。 那么元素的真实值总是$x + add$。 

这将插入和删除变成对标准化值的操作。 剩下的挑战是计算所有实际值的异或：$$\bigoplus (x_i + add)$$现在，我们使用逐位 DP 间接维护归一化值的多重集及其 XOR 结构。 关键的想法是，对于每个位，在应用全局移位后跟踪有多少元素设置了该位，而不单独更新每个元素。 

我们独立处理位，模拟添加常量如何影响二进制表示。 我们不接触所有元素，而是维护哈希映射中标准化值的频率，并使用以下恒等式逐位重建 XOR：

 如果奇数个元素设置了该位，则 XOR 中的某个位为 1。 

对于每个查询，我们不会从头开始重新计算。 我们仅使用存储的频率和当前的全局移位、使用位级贡献来调整计数并重新计算异或。 

重要的结构转变是我们从不存储实际值，只存储移位代表的计数，并且我们解释位$x + add$在飞行中。

 | 最优（惰性移位+位重建）| O(q log A) | O(q log A) | O(n) | 已接受 |

 ## 算法演练

 我们维护“基值”的频率图和全局偏移值`add`。 

1. 初始化`add = 0`并将所有初始值及其频率存储在哈希图中。 我们也不维护直接异或，因为它在移位时发生变化。 
2. 插入值`v`，我们将其存储为`v - add`。 这确保了当应用全局平移时，实际值变得正确。 这种标准化使得所有未来的全局增量都是 O(1)。 
3. 删除值`v`，我们也在平移坐标系中将其解释为`v - add`并减少其频率（如果存在）。 如果缺席，我们什么也不做。 
4. 对于增量全部操作，我们只需这样做`add += 1`。 这就是整个技巧：我们避免接触任何存储的元素。 
5. 每次操作后，我们重新计算所有值的实际形式的 XOR。 为此，我们迭代频率图中所有不同的存储键，并逐位计算它们的贡献，如下所示`(key + add)`。 
6. 为了计算异或，我们维护一个累加器。 对于每个存储的密钥和频率`cnt`，我们检查每个位的位置。 如果`cnt % 2 == 1`，我们异或`(key + add)`进入答案。 

关键的简化是，即使在加法下值发生变化，计数奇偶校验对于异或来说才是重要的，因此重复项自然会崩溃。 

### 为什么它有效

 The invariant is that the multiset of real values is always exactly the multiset of`(key + add)`超过存储的密钥。 插入和删除保留了这种表示，因为我们总是转换为移位的坐标系。 全局增量统一影响所有元素，这完全通过调整来捕获`add`。 由于 XOR 仅取决于出现的奇偶校验，因此在该移位空间中保持正确的重数可以保证最终的 XOR 在每一步都是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))

    freq = defaultdict(int)
    add = 0

    for x in arr:
        freq[x] += 1

    def get_xor():
        res = 0
        for k, cnt in freq.items():
            if cnt % 2 == 1:
                res ^= (k + add)
        return res

    for _ in range(q):
        tmp = input().split()
        t = int(tmp[0])

        if t == 1:
            add += 1

        elif t == 2:
            v = int(tmp[1])
            freq[v - add] += 1

        else:
            v = int(tmp[1])
            key = v - add
            if freq[key] > 0:
                freq[key] -= 1
                if freq[key] == 0:
                    del freq[key]

        print(get_xor())

solve()
```代码直接遵循规范化思想。 字典将值存储在坐标系中，其中全局增量被分解。 这`add`变量表示应用于所有元素的累积移位。 将翻译值插入和删除回此标准化空间。 

XOR 重新计算利用了配对抵消的事实，因此只有奇数频率才重要。 Each time we reconstruct real values by adding`add`。 

一个微妙的点是，删除必须在递减之前检查存在性； 否则我们会错误地引入负计数。 删除零个条目可以使字典在实践中保持足够小。

 ## 边缘情况

 所有元素都相同的情况强调删除和异或取消。 用于输入`5 3`和`2 2 2 2 2`，逐个删除出现的位置始终保持 XOR 一致，因为奇偶校验保持不变，直到删除最后一个元素。 

具有重复全局增量的情况测试是否`add`累加器单独正确地代表了许多操作。 即使经过数百次增量，存储的映射也不会发生结构变化，因此正确性完全取决于将值解释为`key + add`。 

删除目标不存在的值的情况可确保稳定性。 如果我们尝试删除移位空间中不存在的值，则频率图必须保持不变，否则异或奇偶校验将被破坏。
