[CF 2204B - 右最大值](https://codeforces.com/problemset/problem/2204/B)

 **标签：** 贪婪
 **求解时间：** 1m 34s

 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并要求模拟一个非常具体的删除过程。 在每个操作中，我们查看当前数组，找到最大元素，如果多个元素共享该最大值，我们选择最右边的一个。 然后，我们删除该元素及其后面的所有内容。 问题是需要多少次这样的操作才能完全清空数组。 

输入提供多个测试用例。 每个测试用例给出数组的长度，后跟数组本身。 约束告诉我们，数组大小最多可达 200,000，测试用例最多可达 10,000 个，但跨测试用例的所有数组大小之和不超过 200,000。 这表明我们需要一个与数组大小大致线性的解决方案，因为任何比每个测试用例的 O(n) 更差的算法都会太慢。 

可能破坏简单解决方案的边缘情况包括严格递增、严格递减的数组或出现多个最大元素的数组。 例如，一个数组`[3, 3, 3]`应该进行一次操作，因为最右边的最大值是最后一个元素，一次性删除整个数组。 总是选择第一个最大值的幼稚实现会错误地模拟多个操作。 

## 方法

 暴力方法实际上会模拟该过程：在每一步中，扫描数组以找到最右边的最大值，删除从该位置到末尾的所有元素，然后重复。 这是正确的，但是每次找到最大值需要 O(n) 时间，在最坏的情况下，我们可以执行 O(n) 操作。 这导致每个测试用例的时间为 O(n^2)，这对于 n = 200,000 来说太慢了。 

最佳解决方案的关键观察是，当我们从右向左删除最大元素时，操作数对应于数组向左延伸的距离。 具体来说，如果我们从右向左遍历数组，跟踪到目前为止看到的最大值，每次当前元素等于这个运行最大值时，我们就知道它将在某些操作中被选择。 我们不需要模拟移除，只需计算最大值“延伸”左边界的段。 这种见解将问题简化为使用几个整数变量的单个反向遍历，即 O(n) 时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从数组末尾开始，初始化一个操作计数器、一个用于跟踪后缀中当前最大值的变量，以及一个指示下一次删除影响的最左边索引的边界标记。 
2. 向后迭代数组。 更新目前为止看到的最大值。 
3. 每当索引与当前删除段的最左边界匹配时，递增操作计数器并将边界移动到扩展该段的下一个最大值的位置。 这是有效的，因为左边的任何最大值最终都会成为下一个操作的新的最右边的最大值。 
4. 继续，直到到达数组的开头。 
5. 返回操作计数器。 

为什么有效：从右向左遍历可确保我们首先考虑每个最大值的最后一次出现。 每次我们碰到要删除的段的左边界时，我们就知道发生了一个操作。 由于段仅由大于先前最大值的元素扩展，因此每个元素最多被考虑一次，从而保证正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ops = 0
        right = n
        current_max = 0
        
        # traverse from right to left
        i = n - 1
        while i >= 0:
            current_max = max(current_max, a[i])
            if i == right - current_max:  # left boundary of next removal segment
                ops += 1
                right = i
                current_max = 0
            i -= 1
        print(ops)

if __name__ == "__main__":
    solve()
```该解决方案使用快速 I/O 并独立迭代每个测试用例。 我们从最右边的元素向左遍历，更新`current_max`反映当前后缀中的最大元素。 当当前索引与最大值定义的段的左边界对齐时，我们计算一次操作并重置下一次操作的边界。 仔细处理边界可确保重叠段不会被重复计算，这是一种常见的差一错误。

 ## 边缘情况

 对于数组`[3, 3, 3]`，该算法从最后一个元素开始，识别索引 2 处最右边的最大值，删除它及其后面的所有元素（在本例中没有），并计算一次操作。 左边界更新，继续遍历，但不需要进一步操作。 输出正确`1`。 

为了`[5, 4, 3, 2, 1]`，考虑的最后一个元素是 1，但最右边的最大值是索引 0 处的 5。索引 0 之后的所有元素都将在单个操作中删除。 该算法正确地计算了一次操作，因为最大值扩展了左边界以覆盖整个数组。
