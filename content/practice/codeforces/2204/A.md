 ## 解决方案
 ## 问题理解

 我们有一排从左到右排列的学生，以及一个根据固定规则确定性移动的球。 每个学生都有一个方向，要么向左，要么向右，这意味着每当球到达该学生时，它就会立即传递给该方向上的相邻学生。 端点是强制的：第一个学生总是从右边经过，最后一个学生总是从左边经过。 

该过程从学生 1 拿球开始。 然后球准确传出$n$次。 在这些传球过程中，球可能会多次重新访问同一个学生，但我们只关心哪些不同的学生至少持球一次。 

因此，问题简化为模拟在线图上的确定性行走，其中每个节点恰好有一个到邻居的出边，并且我们计算从节点 1 开始的固定数量的步骤期间访问了多少个不同节点。 

约束足够小，直接模拟是完全安全的。 和$t \le 10^4$和$n \le 50$， 甚至$O(n^2)$每个测试用例最多导致$2.5 \cdot 10^7$步骤，这完全在 Python 的限制范围内。 

就无效移动而言，不存在棘手的隐藏边缘情况，因为移动始终是定义的。 唯一微妙的一点是步数恰好是$n$，直到稳定或退出界限。 这很重要，因为路径可能会振荡并多次重新访问节点。 

一个天真的错误是假设步行形成一个单调的片段，或者它总是先向右移动，然后向左移动一次。 例如，在`RLRL`，球在 1 和 2 之间无限地弹跳。 错误的贪婪解释可能会错误地假设步行连续扩展，但事实并非如此。 

另一个潜在的错误是忘记计算起始节点（学生 1），因为问题明确表明他们在任何传球发生之前首先收到球。 

## 方法

 所描述的过程已经是完全确定性的，因此最直接的方法是逐步模拟它。 我们维护球的当前位置，并且每次通过后我们根据当前学生中存储的方向更新位置。 我们还保留一个布尔数组或一个学生已经收到球的集合标记。 

准确执行后$n$转换时，我们计算有多少学生被标记为访问过。 

这是有效的，因为每个状态转换都是$O(1)$，而我们只做$n$每个测试用例的转换，因此总复杂度是线性的$n$。 

暴力模拟在这里已经是最佳选择。 不需要循环检测或图压缩，因为$n$最多 50，因此即使在许多测试用例中重复重新计算也仍然微不足道。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟|$O(n^2)$所有测试总计 |$O(n)$| 已接受 |
 | 最佳模拟（相同的想法）|$O(n^2)$所有测试总计 |$O(n)$| 已接受 |

 ## 算法演练

 1. 从位置 1 的球开始，将学生 1 标记为已访问。 这反映了任何移动发生之前的初始条件。 
2. 准确重复$n$次：观察当前学生的方向并将球向左或向右移动。 每次移动对应于跟随当前节点的唯一出边。 
3. 每次移动后，将新位置标记为已访问。 这确保我们捕获所有接收球的节点，而不仅仅是线段的端点。 
4. 完成所有动作后，计算有多少学生被标记为已访问并输出该数字。 

### 为什么它有效

 在任何时刻，球的位置完全由先前位置和该节点处的固定方向决定，这意味着该过程是有向图上的确定性行走，其中每个节点的出度恰好为 1。因为我们显式模拟每个转换，所以我们精确复制此行走的精确轨迹$n$步骤。 统计的每个学生恰好是轨迹至少进入过一次的学生，并且不会遗漏任何学生，因为每次访问发生时都会立即处理。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input().strip())
        s = input().strip()

        # 0-indexed positions
        pos = 0
        visited = [False] * n
        visited[pos] = True

        for _ in range(n):
            if s[pos] == 'R':
                pos += 1
            else:
                pos -= 1
            visited[pos] = True

        out.append(str(sum(visited)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现直接反映了算法中描述的模拟。 数组`visited`跟踪每个学生是否已收到球。 我们初始化位置 0，因为学生 1 从球开始。 每次迭代都会根据字符串中的当前字符更新位置。 

一个微妙的点是移动总是安全的：问题保证第一个角色是`R`最后一个是`L`，所以我们永远不会出界。

 ## 边缘情况

 一个关键的边缘情况是纯振荡行为。 对于像这样的输入`RLRL`，行走永远不会超出前两个节点。 模拟从节点 1 开始，移动到 2，然后立即返回到 1，并重复。 因为我们在每一步都明确标记了访问，所以节点 1 和 2 都被计数，并且不会发生错误扩展。 

另一种情况是完全单调的运动，例如`RRRRRL`。 在这里，球向右移动直到到达终点，访问每个节点，然后后退一次。 模拟确保节点 6 在返回之前也被计算在内，因为我们在每次移动后进行标记，而不仅仅是端点。 

最后一个微妙的情况是最小输入，例如`n = 2`。 该过程仍然从节点 1 开始执行两次移动。模拟会自然地处理此问题：第一次移动到达节点 2，第二次移动返回到节点 1，从而导致两个节点都被访问。
