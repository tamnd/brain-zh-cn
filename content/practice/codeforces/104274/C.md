 ## 解决方案
 ## 问题理解

 我们得到了一个非常小的类似魔方的物体的状态，它已经是一个 1×1×1 立方体，这意味着正好有六个没有内部结构的彩色面。 每个面在空间中都有一个固定位置，输入描述了在该固定方向上的六个标记面上当前可见的颜色。 

从已解决的配置中，每个面都有特定的目标颜色，我们可以应用立方体面的旋转。 每一步都会将一个面（前、后、左、右、上、下）顺时针旋转 90 度，并且重复同一面旋转最多 3 次对应于可见面的不同排列。 目标不是物理模拟任意序列，而是找到最短的移动序列，将给定配置转换为目标配置，其中正面为白色，立方体的其余部分处于由有效立方体旋转引起的一致求解排列。 

关键的结构约束是保证可以使用有效的面旋转从已求解的状态到达输入状态。 这意味着我们完全在由立方体对称性引起的有限状态空间内工作，而不是六种颜色的任意排列。 

每个移动都是可逆的并且成本统一，因此该任务是有限图上的最短路径问题，其中节点是立方体状态，边是面旋转。 隐藏的困难是图很小但没有明确给出，并且对六个面的排列的简单搜索已经建议最多 6 个！ 状态，但有效的立方体旋转将可达状态限制为仅 24 个方向状态。 

一个幼稚的错误是将其视为六个面的完整排列问题，并在 720 个状态上运行 BFS，这仍然很小但不必要，并且模糊了结构。 另一个错误是忽略旋转保留面之间的邻接约束，因此并非所有排列都是有效状态。 

值得强调的一个边缘情况是立方体已经被解决。 例如，输入`1 2 3 4 5 6`对应身份配置，所以答案一定是`0`移动。 任何盲目输出旋转序列的解决方案在这里都是不正确的。 

另一个微妙的情况是多个不同的序列产生相同的最小状态转换。 例如，相反的旋转`L1`和`L3`是相反的，因此本地取消的天真的贪婪方法可能会错过真正的最短解决方案是零步或一步。 

## 方法

 暴力的观点是将立方体的每个状态视为图中的一个节点，并将每个允许的面旋转视为一条边。 从初始配置开始，我们运行广度优先搜索，直到达到目标求解配置。 每个状态都表示为一个 6 元素数组，每次移动都会根据面部旋转规则排列这六个值。 

这种方法是正确的，因为未加权图上的 BFS 总是能找到最短路径。 问题不在于正确性，而在于我们如何表示状态和转换。 如果我们明确列举所有 6 个！ 排列并为每次旋转定义转换，BFS 仍然可以在大约 720 个状态和最多几千个边上工作，这对于约束来说已经是微不足道的了。 

然而，这忽略了更深层次的结构：并非所有排列都是可达的，而可达集恰好是立方体的 24 个旋转方向。 所以完整的排列空间是多余的。 问题归结为认识到立方体的状态空间是立方体的旋转组，其大小为 24。这允许我们预定义所有状态和转换并运行一次 BFS。 

我们可以预先计算每次移动对状态索引的影响，然后对 24 个状态进行 BFS 计算从目标求解状态开始的最短路径。 这为我们提供了从任何输入状态到最佳移动序列的固定查找表。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 所有排列上的强力 BFS | O(6!· 移动) | O(6!) | 已接受但没有必要 |
 | 立方体方向状态上的 BFS | O(24 · 移动) | O(24) | 已接受 |

 ## 算法演练

 我们首先形式化立方体的状态空间。 每个状态对应于刚性立方体 24 种可能方向之一。 我们不是任意跟踪颜色，而是跟踪六个面在旋转下如何排列。 

我们将已解决的状态预定义为每个面都有其目标颜色的配置，并将其视为 BFS 的根。 

1. 我们将每个立方体方向编码为固定顺序的六种面颜色的元组，例如前、后、左、右、上、下。 这种编码唯一地标识了可达空间内的状态，因为旋转保留了邻接结构。 
2. 我们定义了 F、B、L、R、U、D 六个动作中每一个动作的效果。每个动作都是六个面部位置的排列。 例如，旋转正面会循环周围的边缘相邻面，同时保持相对面固定。 我们对这些排列进行硬编码。 
3. 从已解决的状态开始，我们通过重复应用这六个动作对所有可达状态运行 BFS。 对于每个状态，我们存储父状态以及用于到达它的移动。 这在 24 状态图上构造了一个最短路径树。 
4. BFS 完成后，我们构建从状态到其距离的查找，以及从已解决状态到达该状态所需的移动序列。 
5. 给定输入配置，我们将其映射到编码中的状态并直接读取其预先计算的最短序列。 

关键思想是我们反转通常的搜索方向。 我们不是从输入中进行搜索，而是预先计算从已解决状态到每个可能方向的最短路径，这保证了每个查询都成为恒定时间查找。 

### 为什么它有效

 面旋转下的立方体方向空间形成一个有限的连通图，其中每条边具有相等的权重。 来自已解决状态的 BFS 同时计算到每个可达状态的最短距离。 由于每个有效的输入状态都保证可以从已求解的配置中到达，因此 BFS 树涵盖了所有可能的输入。 存储的父指针重建最佳序列，而无需在查询时进行任何重新计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# We assume faces are ordered as [F, B, L, R, U, D]

# Each move is a permutation of indices 0..5
moves = {
    'F': (4, 5, 2, 3, 1, 0),
    'B': (5, 4, 2, 3, 0, 1),
    'L': (0, 1, 4, 5, 3, 2),
    'R': (0, 1, 5, 4, 2, 3),
    'U': (3, 2, 0, 1, 4, 5),
    'D': (2, 3, 0, 1, 5, 4),
}

# Precompute all 24 cube orientations by BFS from identity
from collections import deque

def apply(state, mv):
    perm = moves[mv]
    return tuple(state[i] for i in perm)

start = (1, 2, 3, 4, 5, 6)

dist = {start: 0}
parent = {start: (None, None)}
q = deque([start])

while q:
    s = q.popleft()
    for m in moves:
        ns = apply(s, m)
        if ns not in dist:
            dist[ns] = dist[s] + 1
            parent[ns] = (s, m)
            q.append(ns)

def build_path(state):
    path = []
    while parent[state][0] is not None:
        state, m = parent[state]
        path.append(m + "1")
    return path[::-1]

# read input state
arr = tuple(map(int, input().split()))
res = build_path(arr)

print(len(res))
for x in res:
    print(x)
```该实现将立方体状态编码为 6 元组，并使用 BFS 从已求解的配置中预先计算最短路径。 这`apply`函数是唯一对立方体力学进行编码的地方，并且它应用表示面旋转的固定排列。 

一个微妙的实现细节是我们从不尝试在查询时进行几何推理。 所有几何结构都被推入固定排列表中。 这可以避免错误旋转相邻面或混合方向约定等错误。 

这`parent`地图存储先前的状态和所使用的移动，允许通过回溯重建最短序列。

 ## 边缘情况

 身份状态是最简单但最重要的极端情况。 当输入等于已求解的配置时，BFS 距离为零，并且父指针从不存储任何移动。 重建循环立即终止，产生一个与所需输出格式匹配的空序列。 

第二种情况是看起来像是相对面的独立交换的配置。 对于此类输入，BFS 图可能包含多个长度相等的最短路径。 父指针重建任意选择一个，但仍然保证最小性，因为 BFS 层的距离严格增加。 

第三种情况是立方体在多个轴上出现反转，例如`(6,5,4,3,2,1)`。 尽管这个问题看上去还远没有解决，但它仍在 24 国轨道之内。 BFS 确保通过少量旋转即可达到该目标，并且重建可以正确回溯有效的最小序列，而无需尝试直接解释排列结构。
