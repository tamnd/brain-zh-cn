 ## 解决方案
 ## 问题理解

 我们得到一个人的出生日期和上限年份。 对于每个查询，我们需要计算这个人从出生后一年到给定的结束年份庆祝生日的次数。 

关键的复杂性在于，生日每年仅发生在同一日历日期，但生日为 2 月 29 日的情况除外。在这种特殊情况下，生日仅发生在闰年。 如果一年能被 400 整除，或者能被 4 整除但不能被 100 整除，则该年份被视为闰年。 

因此，任务简化为计算一个范围内有多少年包含日期“D/M”作为有效日历日期。 对于正常日期，每年贡献一个生日。 对于 2 月 29 日，只有闰年有贡献。 

限制很大：最多 100000 次查询，每年最多 2,000,000 次。 这排除了任何每年的模拟。 即使是对每个查询逐年迭代的简单方法，在最坏的情况下也需要多达 2e11 次操作，这是不可行的。 

一个微妙的边缘情况是使用正确的闰年规则正确处理 2 月 29 日。 另一个是确保我们排除出生年份本身，即使生日发生在同年晚些时候，因为问题明确地从下一年开始计算。 

例如，如果该人出生于 2000 年 1 月 1 日，YE 为 2000，则答案为 0。如果出生于 2020 年 2 月 29 日，YE 为 2020，则答案也为 0。 

## 方法

 直接的方法是每年从 Y+1 迭代到 YE，检查该年是否存在生日。 对于大多数日期来说，这是微不足道的，因为每年都包含该日期和月份。 2 月 29 日，我们还检查了跳跃条件。 

这在概念上是可行的，但在最坏的情况下，每次测试的范围长度可能高达 200 万，而对于多达 100000 次测试，这会变得太慢。 瓶颈在于每年重复的检查。 

关键的观察结果是，对于除 2 月 29 日之外的所有日期，答案纯粹是某个范围内的整数计数，因为生日每年总是存在一次。 对于 2 月 29 日，我们只需要计算一个范围内存在多少个闰年。 这将每个查询减少为恒定时间减法或闰年前缀计数。 

为了有效支持闰年计数，我们推导出 [1, N] 中有多少个闰年的公式。 这可以使用 4、100 和 400 的倍数上的包含-排除来计算。一旦我们有了这个函数，每个查询就变成了 O(1)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(T · (YE − Y)) | O(T · (YE − Y)) | O(1) | O(1) | 太慢了 |
 | 最佳| O(T)| O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个查询。 

1、首先，我们严格将有效统计范围设定为从出生年份到结束年份的所有年份，即从Y+1到YE。 这确保我们正确排除出生年份。 
2. 如果生日不是 2 月 29 日，则该间隔内的每一年恰好贡献一个生日。 我们将答案计算为 (YE − Y)。 这是因为该范围内的每一年都对该日期有效。 
3. 如果生日是 2 月 29 日，我们需要计算区间 [Y+1, YE] 中有多少个闰年。 
4. 要计算有多少个闰年 ≤ X，我们使用以下公式：

 楼层(X/4) − 楼层(X/100) + 楼层(X/400)。 

这会计算 4 的倍数，删除无效的世纪年，并添加可被 400 整除的世纪。 
5. [L, R] 中的闰年数计算为 F(R) − F(L−1)，其中 F(X) 是前缀闰年计数。 
6. 我们应用此公式 L = Y+1 且 R = YE，得出最终答案。 

为什么它有效

对于非闰年特殊生日，事件“生日发生”与年份无关并且始终为真，因此计数减少为对某个范围内的整数进行计数。 对于 2 月 29 日，该事件精确地减少为闰年集中的年份成员，这完全符合标准整除规则的特征。 前缀函数F(X)精确计数到X为止的集合，并且减法隔离任何区间，没有重叠或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def leap_count(x):
    if x <= 0:
        return 0
    return x // 4 - x // 100 + x // 400

def solve():
    T = int(input())
    out = []
    for _ in range(T):
        d, m, y, ye = map(int, input().split())
        l = y + 1
        r = ye

        if m == 2 and d == 29:
            if l > r:
                out.append("0")
                continue
            ans = leap_count(r) - leap_count(l - 1)
            out.append(str(ans))
        else:
            if l > r:
                out.append("0")
            else:
                out.append(str(r - l + 1))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案将闰年情况与所有其他日期分开。 辅助函数`leap_count`实施包含排除公式，将闰年计数到阈值。 

对于正常日期，我们计算 [Y+1, YE] 范围内的整数个数，这很简单`r - l + 1`。 对于 2 月 29 日，我们将问题转化为使用前缀差异来计算同一时间间隔内存在多少个有效闰年。 

边界条件`l > r`处理 YE 等于 Y 的情况，确保不会出现负计数。

 ## 边缘情况

 一种极端情况是出生年份与结束年份相同。 对于像 10/5/2000 这样 YE = 2000 的正常日期，从 2001 年开始，区间就变成空了。算法设置 L = Y+1，因此 L > R 并直接返回 0。 

另一个极端情况是 2 月 29 日，其范围不包含闰年。 例如，29/2/2021 到 2023 会生成 L = 2022 和 R = 2023。闰年前缀差异返回零，因为两个端点都不包含闰年。 

最后的边缘情况是接近 2e6 的非常大的年份值。 前缀公式仍然可以安全地工作，因为所有操作都是简单的整数除法，并且不会发生溢出或迭代。
