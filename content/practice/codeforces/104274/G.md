 ## 解决方案
 ## 问题理解

 我们得到一排花，每朵花都有一个由整数表示的类型。 仅当花束对应于该行的连续片段并且该片段恰好包含 K 种不同的花类型时，花店才认为花束“有效”。 

任务是计算有多少个连续子数组具有精确的 K 个不同值。 

输入大小最多可达 300,000 个元素。 任何试图直接检查所有子数组的解决方案在最坏的情况下都需要大约 N 平方的检查，这大约是 10^10 次操作，并且在典型的时间限制内是不可行的。 这立即排除了任何为每个时间间隔独立重新计算不同计数的方法。 

这个问题的一个微妙点是“精确 K 个不同”比“至多 K 个不同”要困难得多。 在滑动窗口技术下，计算具有最多 K 个不同值的子数组表现良好，而精确的 K 需要减少技巧。 

典型的失败案例来自于尝试独立扩展两端而不保持一致的窗口结构。 例如，如果所有元素都是不同的且 K = 2，则简单的扩展可能会重复计数或错过有效段，具体取决于重复项的处理方式。 问题不在于个别检查的正确性，而在于重叠子阵列的计算不一致。 

## 方法

 蛮力的想法很简单。 我们迭代每个左端点，然后扩展右端点，同时跟踪当前段内元素的频率图。 对于每个扩展，我们计算存在多少个不同的值，如果它等于 K，则增加答案。这在逻辑上是有效的，因为它一次性枚举了所有可能的子数组。 

当我们分析复杂性时，问题就出现了。 每次插入维护频率图的时间复杂度为 O(1)，但有 O(N^2) 个子数组，因此总工作量变为 O(N^2)，这对于 N 高达 3 × 10^5 来说太慢了。 

关键的见解是将问题从“恰好 K”转换为两个“最多 K”计数的差异。 如果我们可以有效地计算具有最多 K 个不同值的子数组，那么具有恰好 K 个不同值的子数组的数量就是具有最多 K 的子数组和具有最多 K − 1 的子数组之间的差值。这是有效的，因为每个具有最多 K 的子数组都会对总数做出贡献，并且减去具有最多 K − 1 的子数组会删除所有少于 K 个不同值的情况，仅留下 K。 

“至多 K 个不同”问题非常适合滑动窗口。 我们维护一个窗口 [l, r] 并通过在必要时移动左指针来确保不同元素的数量不超过 K。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N^2) | O(N^2) | O(N) | 太慢了|
 | 最佳 | O(N) | O(N) | 已接受 |

 ## 算法演练

 我们将问题简化为计算 atMost(K) − atMost(K − 1)。 

### 步骤

1. 定义一个函数 atMost(K)，用于对最多包含 K 个不同值的子数组进行计数。 我们将使用滑动窗口来计算它。 
2. 维护当前窗口内元素的频率图以及跟踪当前有多少个值具有非零频率的不同计数器。 
3. 将两个指针 l 和 r 初始化为 0，并初始化一个答案变量 ans = 0。 
4. 在数组上从左向右展开 r。 对于每个新元素 A[r]，增加其频率。 如果该元素第一次出现在窗口中，则增加 unique。 
5.如果distinct变得大于K，则通过向前移动l并减少频率来从左侧缩小窗口，直到distinct再次最大为K。当频率变为零时，递减distinct。 
6. 一旦窗口满足约束，所有以 r 结尾并从 l 到 r 的任意位置开始的子数组都有效。 将 (r − l + 1) 添加到 ans 中。 
7. 重复步骤 4 至 6，直到 r 到达末尾。 
8. 最终答案是 atMost(K) − atMost(K − 1)。 

### 为什么它有效

 在每个位置 r，算法都会维护最小左边界 l，使得窗口 [l, r] 最多包含 K 个不同值。 任何以 r 结尾且早于 l 开始的子数组都会引入至少 K + 1 个不同值，因为向左扩展只会添加元素而不能减少不同计数。 

这创建了一个单调结构：对于每个 r，所有有效的开始形成一个连续的段。 将它们计数为 r − l + 1 可确保每个有效子数组仅计数一次，并且不包含无效子数组。 然后，减法步骤精确地分离出 K 个不同的值，而不会出现重叠问题。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import defaultdict

def at_most(k, a):
    if k <= 0:
        return 0
    freq = defaultdict(int)
    l = 0
    distinct = 0
    res = 0

    for r in range(len(a)):
        if freq[a[r]] == 0:
            distinct += 1
        freq[a[r]] += 1

        while distinct > k:
            freq[a[l]] -= 1
            if freq[a[l]] == 0:
                distinct -= 1
            l += 1

        res += r - l + 1

    return res

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    print(at_most(k, a) - at_most(k - 1, a))

if __name__ == "__main__":
    solve()
```该实现围绕辅助函数 at_most 展开。 频率字典跟踪当前窗口内的元素计数，而不同的则确保我们知道何时违反约束。 while 循环是当窗口变得过于多样化时恢复有效性的关键部分。 

solve中的减法直接实现了从精确K个到最多K个计数的转换。 边缘情况 k = 0 通过提前返回零来处理，因为非空子数组不能有零个不同元素。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N) | 每个指针 l 和 r 在每次 atMost 调用中总计最多移动 N 次 |
 | 空间| O(N) | 频率图存储窗口中活动元素的计数 |

 该解决方案在阵列上运行两次线性传递，因此总复杂度在 N 中保持线性，这完全符合 N 高达 3 × 10^5 的限制。

 ## 边缘情况

 一种边缘情况是当 K 等于 1 时。在这种情况下，由相同元素组成的每个子数组都是有效的。 atMost 转换仍然有效，因为 atMost(1) 对所有统一段进行计数，并且 atMost(0) 正确返回零，因为没有子数组可以具有零个不同值。 

当 K 大于数组中不同值的数量时，会出现另一种边缘情况。 这里 atMost(K) 计算所有子数组，而 atMost(K − 1) 已经等于 atMost(K)，产生零。 滑动窗口永远不会触发完全重置，因为不同的计数器永远不会超过 K，因此只要有可能，整个数组就会被视为单个有效区域。 

最后一个微妙的情况是频繁交替导致左指针反复收缩。 即使在 1,2,1,2,1,2 等模式中，窗口也会振荡，但每次指针移动时每个索引仍最多处理一次，从而保留线性复杂性，同时保持重叠有效段的正确计数。
