 ## 解决方案
 ## 问题理解

 我们得到一个正整数的多重集，并允许以任何顺序排列它们。 选择顺序后，我们重复获取该顺序的前缀并计算每个前缀的 gcd，然后将所有这些 gcd 值相加。 

关键的观察结果是，到目前为止，每个位置的贡献完全取决于前缀 gcd。 当附加一个新数字时，gcd 要么保持不变，要么减少到它的约数。 由于我们可以自由地重新排序，整个问题就变成了如何排列数字，以便大的 gcd 值在它们不可避免地下降之前尽可能长时间地存在。 

约束条件很大：最多$10^5$数量，每个最多$2 \cdot 10^7$。 这排除了任何重新计算许多排列的 gcd 或尝试对排列进行贪婪模拟的方法。 任何超出粗略范围的事情$O(n \log A)$或者$O(n \sqrt{A})$每次测试都会很困难。 

当许多数字共享小除数但没有大的公共结构时，就会出现微妙的边缘情况。 例如，如果所有数字都是互质的，则无论顺序如何，gcd 在第一个元素之后立即折叠为 1。 另一种边缘情况是当一个数字非常大而所有其他数字都将其整除时，如果将其放在第一位，则可以为长前缀保留较大的 gcd。 

## 方法

 暴力策略会尝试所有排列并计算每个排列的分数。 即使固定排列，计算分数也是线性的，因此完整搜索是$O(n! \cdot n)$，完全不可行。 

更合理的一步是贪婪地思考。 假设我们已经有一个前缀 gcd$g$。 如果我们附加一个数字$x$，新的 gcd 变为$\gcd(g, x)$。 最好的结果就是坚持$g$尽可能多的步骤。 这建议尽早放置保留当前 gcd 的数字。 

然而，这仍然留下了核心困难：在每一步我们都需要知道哪些剩余数字最好地维持给定的 gcd，而 gcd 状态取决于所有先前选择的元素。 

关键的结构洞察力是扭转观点。 我们不考虑向前构建排列，而是考虑每个值如何在某个阶段充当前缀的 gcd。 如果我们固定一个值$d$，我们可以问有多少个数可以被$d$，以及有多少个前缀可以准确地维持gcd$d$。 这将问题转化为聚合除数的贡献，而不是模拟排列。 

我们在频率上使用基于除数的 DP：对于每个$d$，我们计算有多少个数组元素可以被整除$d$，然后推理我们可以维持 gcd 等于多久$d$在被迫下降到更小的除数之前。 从大到小处理除数可确保首先考虑更严格的 gcd 状态的贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n! \cdot n)$|$O(n)$| 太慢了 |
 | 频率除数 DP |$O(A \log A)$|$O(A)$| 已接受 |

 ## 算法演练

 我们定义$cnt[x]$作为值的频率$x$，我们的工作倍数可达$A = \max(a_i)$。 

1.计算频率数组$cnt$。 这使我们能够通过聚合倍数来快速了解有多少个元素可以被任意数字整除。 
2. 对于每个整数$d$从 1 到$A$, 计算$f[d]$，可被整除的元素数量$d$。 这是通过迭代多个来完成的$d$。 此步骤将原始值转换为基于除数的结构。 
3.定义DP数组$dp[d]$， 在哪里$dp[d]$表示我们可以从 gcd 恰好为的段中获得的最大贡献$d$，假设我们只使用可被整除的数字$d$。 
4. 流程$d$按降序排列。 对于每个$d$，我们首先计算有多少个元素可以被整除$d$。 如果我们决定前缀 gcd 变为$d$，每个这样的位置至少贡献$d$。 
5. 然而，在能被$d$，有些实际上会强制 gcd 下降到$d$的除数。 为了纠正多算的情况，我们减去已经分配给倍数的捐款$d$，对倍数使用包含-排除。 
6. 将答案累加为所有答案的总和$d$按我们可以维持 GCD 的步数加权的贡献数$d$在转换为较小的值之前。 

关键思想是每个前缀 gcd 转换都受整除结构控制，并且每个数字仅参与除数链。 

### 为什么它有效

 前缀的 gcd 始终是该前缀中每个元素的除数。 这意味着每个前缀状态唯一对应于某个除数$d$，一旦我们用除数来解释该过程，每个元素都会独立地对其支持的所有除数状态做出贡献。 从大到小的处理确保了当我们计算$d$，所有更强的约束（$d$）已经被考虑在内，防止重复计算并保持累积前缀长度的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    A = max(a)

    cnt = [0] * (A + 1)
    for x in a:
        cnt[x] += 1

    # f[d] = how many numbers divisible by d
    f = [0] * (A + 1)
    for d in range(1, A + 1):
        s = 0
        for m in range(d, A + 1, d):
            s += cnt[m]
        f[d] = s

    # dp[d] = best contribution where gcd-state is exactly d
    dp = [0] * (A + 1)

    ans = 0

    for d in range(A, 0, -1):
        if f[d] == 0:
            continue

        # total positions we could potentially assign gcd divisible by d
        total = f[d]

        # subtract contributions from multiples (inclusion-exclusion)
        for m in range(2 * d, A + 1, d):
            total -= dp[m]

        if total > 0:
            dp[d] = total
            ans += dp[d] * d

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先构建频率，然后将它们转换为除数重数计数。 dp 数组在除数上自下而上使用：计算时$d$，我们减去已经分配给其倍数的所有贡献，确保每个“前缀容量”单位都分配给恰好一个 gcd 级别。 最终的答案是将每个 gcd 值乘以它可以支配的前缀位置的数量。 

一个常见的陷阱是以错误的方向迭代除数。 如果从小到大处理，倍数还没有解决，减法就会失败。 另一个微妙的点是，我们从不显式地构造排列，因为 DP 已经隐式地编码了最优排序。

 ## 边缘情况

 当所有数字都相等时，gcd 永远不会改变，因此每个前缀贡献相同的值。 该算法将全部容量分配给该值的除数，并且没有减法将其删除，因为不存在倍数，从而产生$n \cdot x$。 

当所有数字都是成对互质时，每个$f[d]$为零，除了$d=1$。 DP将一切分配给$d=1$，答案就变成了$n$，匹配所有前缀 gcd 在第一个元素之后立即变为 1 的事实。 

当一个数字很大并且所有其他数字都除它时，较高的除数首先消耗大部分容量，并且算法正确地对它们进行优先级排序，匹配最大元素首先放置的最佳顺序。
