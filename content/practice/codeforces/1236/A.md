 ## 解决方案
 ## 问题理解

 我们得到了三堆石头。 从这些堆中，爱丽丝可以重复执行两种动作。 一次移动会消耗第一堆中的一颗石子和第二堆中的两颗石子。 另一个动作消耗第二堆中的一颗石子和第三堆中的两颗石子。 每一步都会增加她收集的分数：每移走一块石头都会计入她的总分。 

该过程是完全灵活的，但每个操作都会降低未来操作的可用性，因为两个操作都会争夺第二堆中的石头。 任务是选择一个移动序列，使移除的石子总数最大化。 

输入尺寸较小，每堆最多包含 100 个石子，最多包含 100 个测试用例。 这立即排除了对复杂图搜索或大状态动态编程的任何需要。 在这些约束下，即使是对可能的移动计数进行三次或二次枚举也是安全的。 

一个微妙的问题来自于共享的中间堆。 这两个操作都会消耗其中的石头，因此像“总是尽可能多地获取第一个操作”这样的贪婪策略可能会阻止稍后更好地使用第二个操作。 

例如，如果我们尽早积极地使用第一个操作，我们可能会以一种阻止与第三堆配对的方式耗尽第二堆，从而可能丢失第二类型的许多动作。 这种相互依赖是核心困难：对一项操作的局部贪婪会降低全局最优性。 

## 方法

 思考该问题的一种强力方法是模拟所有可能的操作序列。 在每一步中，我们都会选择第一个或第二个操作（如果它有效）。 这形成了一个搜索树，其中每个节点最多分支为两个状态。 然而，在最坏的情况下，深度可能高达 200 个操作，并且分支因子使该指数呈指数增长，即使输入大小很小，也很快变得不可行。 

关键的观察是，我们实际上并不关心操作的顺序，只关心每个操作使用了多少次。 如果我们固定第一个操作使用 x 次，第二个操作使用 y 次，则可行性仅取决于资源限制：

 第一堆必须满足 x ≤ a，第三堆必须满足 2y ≤ c，第二堆必须满足 2x + y ≤ b。 

每个操作恰好为答案贡献 3 个石子，因此目标变为最大化 3(x + y)。 

这将问题简化为检查 x 的所有有效值并计算最佳对应的 y。 由于 x 的界限最多为 100，因此我们可以有效地迭代所有可能性。 

探索序列的蛮力想法变成了更简单的计数枚举，并且操作之间的依赖关系通过第二堆的约束得到了干净的处理。

 ## 算法演练

1.修复我们应用第一个操作的次数。 将此值称为 x。 我们可以尝试从 0 到 a 的每个 x，因为第一堆限制了我们可以使用它的次数。 
2.选择x后，我们考虑它对第二堆的消耗。 第二堆失去了 2x 颗石子，因此剩余数量为 b - 2x。 该剩余资源决定了仍然可以进行多少次第二操作。 
3. 计算可以执行多少次第二操作。 每次第二次操作都需要从第二堆中取出一颗石子，从第三堆中取出两颗石子，因此最大值受到剩余的第二堆石子和第三堆中可用的三块石子的限制。 得出 y = min(b - 2x, c // 2)。 
4. 将此配置收集的石子总数计算为 3(x + y)。 我们跟踪所有 x 的最大值。 
5.测试所有可行的x值后，输出最好的结果。 

尝试所有 x 值背后的关键思想是，一旦 x 被固定，剩余的结构对于 y 来说变得完全贪婪和确定性，因此不需要进一步的决策。 

### 为什么它有效

 第二堆是两个操作之间唯一共享的资源，因此整个优化简化为决定为第一个操作和第二个操作保留多少资源。 一旦通过选择 x 修复了该分割，两个操作就会独立消耗不同的资源，从而使余数问题变得贪婪和线性。 这保证了操作的交错不能优于 x 和 y 的固定分配。
