 ## 解决方案
 ## 问题理解

 我们有多种物品，每种物品的供应量都是无限的。 我们还有几个不同的盒子，每个盒子属于不同的朋友，因此盒子都贴有标签，不能交换。 

对于每种物品，爱丽丝都会选择一个盒子子集来放入该物品。 在任何一个盒子里，她都不允许放置超过一件相同种类的物品，但该限制会自动满足，因为某种物品要么被放入盒子中，要么不被放置在那里。 关键的限制是每种类型必须至少出现在一个框中，因此没有一种类型是完全未使用的。 

因此，问题归结为计算我们可以将 m 个标记框的非空子集分配给 n 种中的每一种的方式。 

每种类型在选择方面都是独立的，但“每种类型在某个地方至少使用一次”的全局要求已经针对每种类型强制执行，因此不同类型之间不存在耦合。 微妙之处不在于种类之间的相互作用，而是正确解释每种种类选择盒子的子集，并且所有子集必须非空。 

输入大小高达 10^9，因此任何枚举子集、迭代框或在 n 或 m 上使用动态编程的方法都是不可能的。 即使每个测试用例的 O(n) 或 O(m) 也太大了。 该解决方案必须将所有内容简化为可使用模幂在对数时间内计算的封闭式表达式。 

常见的失败情况是将条件错误地解释为独立地为每个框分配类型的子集，这会导致计数 (2^n - 1)^m 或类似的错误表达式。 另一个错误是忘记不允许对每种类型进行空选择，这将错误地包括零分配。 

## 方法

 首先关注单一类型。 对于一种固定类型，我们决定它出现在哪些框中。 由于有 m 个不同的盒子，因此每个盒子要么被选择，要么不被选择。 这给出了 2^m 个可能的子集。 然而，空子集是被禁止的，因为每种类型必须至少出现在一个框中，因此一种类型的有效选择数为 2^m - 1。 

现在考虑多种。 每种类型都会对盒子的非空子集进行自己的独立选择。 由于不同种类的选择不会相互干扰，因此我们将所有 n 种的选择数量相乘。 得到 (2^m - 1)^n。 

这是关键的结构简化：问题不在于在盒子之间分配对象，而在于为每种类型分配容器的子集。 类型的独立性将组合数学折叠成简单的幂表达式。 

蛮力的想法是迭代每种类型的所有盒子子集，然后强制执行全局约束。 那将是 O(2^m * n)，即使 m = 20 这也是不可能的，更不用说 10^9 了。 每种类型都是独立的这一观察结果消除了任何枚举的需要。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 子集的暴力枚举 | O(n·2^m) | O(n·2^m) | O(1) | O(1) | 太慢了 |
 | 模幂闭式 | O(log n + log m) | O(log n + log m) | O(1) | O(1) | 已接受 |

 ## 算法演练

1.观察到，对于一个固定的种类，每个盒子独立决定是否包含该种类。 这为一种类型提供了 2^m 种可能的分配。 
2. 排除没有盒子包含该种类的情况，因为每种种类必须至少出现一次。 这将计数减少到 2^m − 1。 
3. 独立对待每种类型，因为不同类型的选择不会相互影响。 这种独立性允许各种可能性的倍增。 
4. 将每种计数求 n 次方，得到 (2^m − 1)^n。 
5. 使用快速二进制求幂计算 2^m 模 MOD。 
6. 在模运算下小心减 1，以避免出现负值。 
7. 再次使用模幂将结果求 n 次方。 

为什么有效：每个有效配置都是通过为每种类型独立选择一个非空的框子集来唯一确定的。 全局配置和 m 元素集的 n 个非空子集的元组之间存在双射。 由于笛卡尔乘积结构准确成立，因此计数乘法是准确的并且不会发生过度计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modexp(a, e):
    res = 1
    a %= MOD
    while e > 0:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

n, m = map(int, input().split())

# number of non-empty subsets of boxes for one kind
base = modexp(2, m) - 1
base %= MOD

# total ways
ans = modexp(base, n)

print(ans)
```该解决方案首先使用快速求幂计算 2^m 模 MOD。 减 1 会删除空子集，并且必须对 MOD 进行模运算以避免出现负值。 得到的碱基代表一种类型的有效选择。 然后第二次求幂将该基数提高到 n，反映了每种子集的独立分配。 

一个常见的实现陷阱是忘记在减法后取模，这可能会产生负中间值并破坏后续的求幂。 另一个微妙的问题是假设 Python 的内置 pow 本身就足够了，而无需在模运算下仔细处理负一。

import sys, io

MOD = 10**9 + 7

def modexp(a, e):
    res = 1
    a %= MOD
    while e > 0:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m = map(int, input().split())
    base = modexp(2, m) - 1
    base %= MOD
    return str(modexp(base, n))

 ## 边缘情况

 当 m = 1 时，每种类型只能放入单个框中，因此只有一个有效子集。 该公式给出 2^1 − 1 = 1，并且提高到 n 使其保持 1，符合所有类型都必须进入唯一可用盒子的直觉。 

当 n = 1 时，问题简化为为单一类型选择框的任何非空子集。 该公式正确地得出 2^m − 1。例如，当 m = 3 时，结果为 7，匹配所有可能的位置。 

一个潜在的失败情况是忘记为空子集减 1。 如果错误地使用 2^(m·n)，则会过度计算某些类型从未放置的配置。 正确的结构强制每类非空，这就是为什么减法必须在求幂之前发生。
