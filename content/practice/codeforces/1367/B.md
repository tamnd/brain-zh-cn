 ## 解决方案
 ## 问题理解

 我们得到一个数组，其中每个位置都有固定的“所需奇偶校验”：偶数索引必须包含偶数，奇数索引必须包含奇数。 我们可以使用任意两个位置之间的交换来重新排列数组，并且我们想知道满足所有奇偶校验要求所需的最小交换次数，或者确定根本无法完成。 

重新解释任务的一个有用方法是将每个位置视为具有目标类型、偶数索引或奇数索引，并且每个值也具有类型、偶数值或奇数值。 目标是排列值，以便类型匹配位置要求。 

由于交换不受限制，因此该结构与邻接或排序无关，仅与两组之间的不匹配计数有关。 

约束很小：n 最多为 40，并且最多有 1000 个测试用例。 这意味着每个测试用例的 O(n) 或 O(n log n) 解决方案很容易就足够了，甚至 O(n^2) 解决方案也能轻松通过。 然而，问题的结构表明我们应该能够通过计算不匹配而不是模拟交换来在线性时间内解决每个测试用例。 

当偶数值的数量与偶数索引位置的数量不匹配时，会出现微妙的边缘情况。 例如，如果 n 为 3，则索引 0 和 2 需要偶数，因此我们正好需要两个偶数值。 如果数组只有一个偶数值，则无论进行多少交换都无法解决此问题，因为交换不会改变存在的偶数数量。 

当所有内容都已匹配奇偶校验时，会出现另一种边缘情况。 在这种情况下，答案是零，如果一个简单的交换策略试图“修复”已经正确的位置，它仍然可能会错误地计算不必要的操作。 

## 方法

 强力解释是将问题视为搜索数组的排列。 我们可以尝试所有可能的方法来重新排列元素并计算达到每个有效配置所需的交换次数。 然而，排列的数量是 n！，即使 n = 40，这也是一个天文数字。即使我们尝试根据排列之间的交换距离进行推理，状态空间仍然太大。 

关键的简化来自于观察到只有奇偶性才重要，而不是实际值。 每个元素都属于两个类别之一：偶数或奇数。 每个索引也属于两个类别之一：偶数位置或奇数位置。 问题归结为这两个分区之间的匹配计数。 

如果我们计算每个奇偶校验存在多少个索引以及每个奇偶校验有多少个元素，我们会立即看到解决方案是否可能。 如果计数不匹配，则无法重新排列来修复它。 

一旦可行性确定，剩下的问题是需要多少次互换。 错位奇偶位置元素和错位奇偶位置元素之间的每次交换都会立即修复两个不正确的位置。 这种配对结构直接决定了答案。 

蛮力之所以有效，是因为它尝试显式构造有效的排列，但它失败了，因为它没有利用奇偶校验的二进制结构。 只有不匹配的计数才重要的观察结果将问题简化为计数和配对不匹配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（尝试排列）| O(n!) | O(n) | 太慢了 |
 | 奇偶校验不匹配计数 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们专注于一个测试用例。

1. 计算有多少个数组位置需要偶数值。 这些正是索引 0、2、4 等。 令其为 need_even_positions。 
2. 计算数组中有多少个偶数。 令其为have_even_values。 这决定了有多少元素可用于满足偶数位置。 
3. 如果have_even_values 不等于need_even_positions，则返回-1。 原因是交换不能改变偶数值的总数，因此如果总数不一致，则不可能满足所有约束。 
4. 通过扫描数组计算失配。 对于每个索引 i，如果 i 是偶数但 a[i] 是奇数，则该位置是偶数值的赤字。 如果 i 是奇数但 a[i] 是偶数，则这是偶数值的剩余放置错误。 
5. 令mismatch_even_to_odd 为位于奇数索引中的偶数值的数量。 这等于需要另一方纠正的位置数量。 
6. 最小交换次数为mismatch_even_to_odd，因为错误放置的偶数值和错误放置的奇数之间的每次交换都会同时修复两个位置。 

### 为什么它有效

 每个有效的交换最多可以修复两个不正确的位置，并且每个不正确的位置恰好属于两种对称失配类型中的一种。 一旦可行性确保所需奇偶校验槽和可用奇偶校验值的数量相等，不匹配就会形成完美对。 每次交换都会解决一对，而不会在其他地方创建新的不匹配，因此对这些对进行计数即可得出最佳操作数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    need_even = (n + 1) // 2
    have_even = sum(1 for x in a if x % 2 == 0)
    
    if have_even != need_even:
        print(-1)
        continue
    
    mismatches = 0
    for i, x in enumerate(a):
        if i % 2 != x % 2:
            if i % 2 == 0:
                mismatches += 1
    
    print(mismatches)
```该解决方案首先计算存在多少个偶数索引，即必须用偶数填充的位置数。 然后它会计算数组中存在多少个偶数值。 这种可行性检查至关重要，因为交换无法更改值的多重集。 

仅当偶数索引包含奇数时，不匹配计数循环才会递增。 这是足够的，因为每个这样的不匹配必须与奇数索引处的相应相反不匹配配对，并且仅计算一侧可以避免重复计算交换。

## 测试用例```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        need_even = (n + 1) // 2
        have_even = sum(x % 2 == 0 for x in a)
        
        if have_even != need_even:
            out.append("-1")
            continue
        
        mismatches = 0
        for i, x in enumerate(a):
            if i % 2 == 0 and x % 2 == 1:
                mismatches += 1
        
        out.append(str(mismatches))
    
    return "\n".join(out)

 ## 边缘情况

 如果值为偶数，则大小为 1 的最小数组始终满足条件，因为索引 0 需要偶校验。 由于未检测到不匹配，该算法正确返回零交换。 

当数组具有正确数量的偶数值但它们都位于错误的位置时，可行性通过，但不匹配计数会产生所需的确切交换数量。 每次交换对应于将偶数索引元素与奇数索引元素配对，并且没有其他结构影响结果。
