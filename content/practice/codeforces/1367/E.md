 ## 解决方案
 ## 问题理解

 我们得到了多组彩色珠子，其中每个珠子只是一个小写字母。 从这些珠子中，我们要选择一些子集并将其排列成一个圆圈，形成一条项链。 排列是圆形的，因此旋转很重要，但没有固定的起点。 

如果将每颗珠子沿圆周向前移动 k 个位置而项链保持不变，则该项链被称为 k-beautiful。 换句话说，如果将圆旋转 k 步，颜色序列看起来与开始时的颜色序列相同。 

对于每个测试用例，我们希望在这样一个 k 美丽的圆形排列中具有最大可能的珠子数量，但受到我们只能使用给定多重集中可用的珠子的约束。 

键输入是描述可用珠子的字符串，以及定义旋转对称要求的参数 k。 输出是一个整数，即满足此对称性和可行性约束的圆形排列的最大长度。 

约束足够小，所有测试用例中的珠子总数最多为 2000 个。这会立即排除每个测试用例比大约 O(n^2) 更糟糕的情况，并使得尝试所有候选长度并通过快速检查验证每个长度变得现实。 

一种经常失败的天真的解释是认为我们只是简单地匹配频率或贪婪地构建周期字符串。 例如，如果 k 很大，人们可能会错误地认为对称性无关紧要。 考虑像 n = 5、k = 4 这样的情况，并且所有珠子都是不同的。 一种天真的贪婪方法可能会尝试形成长度 5，但实际上，对称约束强制采用强大的结构，该结构可能只允许更小的有效周期，具体取决于频率分布。 

另一个微妙的失败案例是忽略了循环约束创建的位置循环。 例如，如果 k = 2 并且长度为 6，则位置将分为 (0,2,4) 和 (1,3,5) 等循环。 独立处理位置的解决方案会过度计算可用性，因为每个周期都需要相同的字符。 

## 方法

 蛮力策略是尝试从 1 到 n 的每个可能的长度 L，并检查我们是否可以构建该长度的 k 条美丽项链。 对于每个固定的 L，我们模拟旋转规则所施加的结构。 

关键的结构事实是，旋转 k 意味着索引以循环方式连接。 如果我们将位置 0 标记为 L−1，则位置 i 必须匹配位置 (i + k) mod L。重复此约束会将索引划分为不相交的循环。 在每个循环内，所有位置必须包含相同的字母。 

循环数由L和k的最大公约数决定。 如果我们定义 g = gcd(L, k)，则有 g 个循环，每个循环的大小为 m = L / g。 每个周期的行为就像一个必须用一个字母填充的“槽”，但填充一个槽会消耗该字母的 m 个副本。 

因此，对于固定的 L，问题就变成了：我们有 g 个槽，每个槽需要 m 个相同的珠子，并且我们有字母频率。 每个字母c最多可以贡献floor(freq[c] / m)个槽。 我们只需要检查所有字母的可用槽总数是否至少为 g。 

暴力破解之所以有效，是因为检查 1 L 的可行性只需 26 次操作。 故障点是 L 上的外循环，该循环运行最多 2000 个，每个测试用例进行大约 52,000 次检查，完全在给定总输入大小的限制内。 

除了这个观察之外，不需要动态编程或图搜索，因为循环分解完全线性化了结构。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 通过可行性检查对 L 进行暴力破解 | 每个测试用例 O(n log n)（包括 gcd）| O(1) 额外 | 已接受 |
 | 预计算/DP | 不需要 | O(1) | O(1) | 矫枉过正|

 ## 算法演练

 我们迭代所有可能的候选项链长度，并测试每个项链长度是否可以在对称约束下构造。 

1. 对于候选长度 L，计算 g = gcd(L, k)。 该值决定了位置如何在旋转 k 的情况下分裂成独立的循环。 如果两个位置处于同一周期，则它们必须共享相同的颜色。 
2. 计算 m = L / g，即每个周期的大小。 分配给一个周期的每个选定颜色必须提供 m 个相同的珠子。 
3. 统计输入字符串中所有 26 个字母的出现频率。 这对所有 L 都重复使用。 
4. 对于每个字母c，计算它可以支持多少个完整周期，即freq[c] // m。 这是我们可以分配这种颜色的周期数。 
5. 将所有信件的贡献相加。 如果总数至少为 g，则可以为所有循环分配颜色，这意味着存在长度为 L 的有效项链。 
6. 跟踪可行性成立的最大 L。 

此检查背后的原因是，一旦我们确定了每个周期的颜色，每个周期都是独立的，并且每个周期消耗完全相同的 m 个相同的珠子。 因此，可行性降低为将 g 个相同的“周期需求”打包到可用的频率预算中。 

### 为什么它有效

 旋转约束强制沿变换 i → i + k mod L 的轨道相等。这些轨道正是 gcd(L, k) 循环。 任何有效的项链在每个轨道上都必须保持不变。 相反，对循环的任何颜色分配都会自动满足旋转约束，因为移动 k 只会排列每个循环内的位置。 可行性检查将供应（字母计数）与需求（大小为 m 的周期）相匹配，因此它准确地表征了可构造长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()

        freq = [0] * 26
        for ch in s:
            freq[ord(ch) - 97] += 1

        ans = 1

        for L in range(1, n + 1):
            from math import gcd
            g = gcd(L, k)
            m = L // g

            total = 0
            for f in freq:
                total += f // m

            if total >= g:
                ans = L

        print(ans)

if __name__ == "__main__":
    solve()
```该实现直接反映了先前导出的可行性条件。 每个测试用例计算一次频率数组。 对于每个候选长度 L，我们重新计算 gcd 并导出循环结构。 超过 26 个字母的内部循环确保每个 L 的持续工作。 

一个微妙的点是我们从来没有明确地构建项链。 所有推理都是根据循环计数完成的，这避免了任何组合爆炸。 

## 工作示例

 考虑一个简化的实例：n = 6，k = 3，s =“abcbac”。 

我们评估可能的长度，重点关注 L = 6。 

对于 L = 6，g = gcd(6, 3) = 3，因此有 3 个循环，每个循环的大小为 m = 2。每个循环需要两个相同的珠子。 频率计数使我们能够检查每个字母可以提供多少对。 

| 左 | g = gcd(L,k) | m = 升/克 | 每个字母的可用周期| 总周期| 可行|
 | ---| ---| ---| ---| ---| ---|
 | 6 | 3 | 2 | a:1、b:1、c:1 | 3 | 是的 |

 由于我们可以支持 3 个周期，因此长度 6 是可以实现的。 

现在考虑 n = 3、k = 6、s = "aaa" 的情况。 

对于 L = 3，g = gcd(3, 6) = 3，因此 m = 1。每个周期都是一个位置，因此不存在超出可用性的限制。 每个字母贡献 freq[c] // 1 个周期，总共 3 个周期，与 g 匹配。 

| 左 | 克| 米 | 总周期| 可行|
 | ---| ---| ---| ---| ---|
 | 3 | 3 | 1 | 3 | 是的 |

 这表明当k大于L时，结构退化为独立位置。

 ## 边缘情况

 像单个珠子这样的最小长度情况表明，由于 g = 1 和 m = 1，该算法始终接受 L = 1，因此每个频率阵列都满足该条件。 

仅当 L = 1 时，k = 1 才会强制长度为 L 的循环中的每个位置折叠成单个循环。对于较大的 L，m = L 并且只有一种颜色可以填充整个结构，可行性检查正确捕获了这一点，因为除非所有珠子都相同，否则地板（freq[c] / L）变为零。 

k 大于 L 的情况类似于 g = L 的恒等旋转，使每个位置都有自己的循环。 该算法正确地简化为检查可用珠子总数是否覆盖 L 个位置，这与通过 m = 1 隐式强制执行的频率和条件相匹配。
