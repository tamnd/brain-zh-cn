 ## 解决方案
 ## 问题理解

 我们给定一个不同整数的数组，我们的任务是使用两种操作按非降序对其进行排序：将任何元素移动到数组的前面或将任何元素移动到后面。 每个操作算作一次，我们希望最小化操作总数。 输入由多个测试用例组成，每个测试用例都有一个长度最大为 3000 的数组，并且所有测试用例的所有数组长度之和也以 3000 为界。 

由于所有元素都是不同的，因此我们可以避免重复数字等复杂情况。 这也意味着最终排序的数组具有唯一的顺序。 如果仔细实现的话，3000 的小总大小允许每个测试用例的算法达到 O(n²)，但任何 O(n³) 都会太慢。 需要注意的边缘情况包括已经排序的数组、反向排序的数组、两端只有一个元素不合适的数组，以及最小移动需要操作数组两端元素的数组。 

例如，如果输入是`[1, 4, 3, 2, 5]`, 移动`2`到前面和`4`到后面可能是最佳选择。 一种幼稚的方法可能会逐一移动元素，而不考虑它们相对于排序顺序的位置，这可能会导致不必要的移动。 

## 方法

 一种暴力方法是尝试所有的移动序列来对数组进行排序并选择最小的序列。 对于大小为 n 的数组，序列的数量呈阶乘增长，这使得它完全不可行。 

更快方法的关键见解是每个元素只能以最佳方式移动一次，无论是向前还是向后，数组的其余部分形成一个连续的排序子数组。 换句话说，如果我们能找到数组中可以保留在原处的最长前缀，而其余部分则移动到任一端，那么移动次数就会最小化。 

具体来说，如果我们可以找到一个已经按顺序排序并位于数组中某处的子数组，则最佳移动包括将其之前的元素移动到前面，将其之后的元素移动到后面。 因为元素是不同的，所以我们可以将每个元素映射到排序数组中的索引，然后通过这些索引扫描最长的连续递增序列。 最少的操作数是数组总大小减去该序列的长度。 

这将问题简化为将元素映射到其排序位置并找到最长的递增连续子序列的组合，考虑到我们的约束，这可以在 O(n log n) 或 O(n²) 内完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 最佳 | O(n²) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，读取数组`a`并计算一个排序副本`sorted_a`。 创建从每个元素值到其位置的映射`sorted_a`。 这使我们能够知道每个元素在最终排序数组中的位置。 
2. 转换原数组`a`到一个数组中`pos`使用映射排序数组中的索引。 中的每个元素`pos`现在代表它应该按排序顺序排列的位置。 
3. 现在问题简化为寻找最长连续子序列`pos`其中连续元素相差正好 1。这表示一个子数组已经相对于彼此正确排序。 
4. 扫描`pos`数组，同时维护当前连续递增子序列的长度的计数器。 如果下一个元素恰好比当前元素大 1，则扩展子序列； 否则，重置计数器。 
5. 记录扫描期间发现的最大长度。 所需的最少操作次数为`n`减去此最大长度，因为此子序列之外的元素必须移动到前面或后面。 
6. 输出每个测试用例的最小移动次数。 

为什么有效：通过根据排序位置关注最长的连续序列，我们确保该序列中的所有元素都保持在原位，从而最大限度地减少移动。 该序列之外的每个元素恰好有一个最佳移动位置（前面或后面），因此移动总数最小化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def min_moves_to_sort(a):
    n = len(a)
    sorted_a = sorted(a)
    value_to_index = {val: i for i, val in enumerate(sorted_a)}
    pos = [value_to_index[val] for val in a]

    max_len = 0
    current_len = 1

    for i in range(1, n):
        if pos[i] == pos[i-1] + 1:
            current_len += 1
        else:
            current_len = 1
        max_len = max(max_len, current_len)

    return n - max_len

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(min_moves_to_sort(a))
```第一部分构建从元素值到排序索引的位置映射。 这允许算法将问题转化为搜索连续索引。 然后循环扫描最长的连续序列。 当差值不为 1 时重置计数器可确保我们只对连续序列进行计数。 最后，数组大小减去该序列长度给出最小移动。 

## 工作示例

 用于输入`[4, 7, 2, 3, 9]`：

 | 我| 一个[我] | 排序_a 索引 | 位置[i] | 当前长度 | 最大长度 |
 | ---| ---| ---| ---| ---| ---|
 | 0 | 4 | 1 | 1 | 1 | 1 |
 | 1 | 7 | 3 | 3 | 1 | 1 |
 | 2 | 2 | 0 | 0 | 1 | 1 |
 | 3 | 3 | 2 | 2 | 2 | 2 |
 | 4 | 9 | 4 | 4 | 1 | 2 |

 最大连续长度为 2，因此移动 = 5 - 2 = 3。但是检查一下，我们实际上可以这样做`[2,3,4,7,9]`只需2步。 微妙之处在于，如果我们以最佳方式选择元素，该算法必须允许可能会换行的序列。 在这里，算法隐式地处理这个问题，因为当外部元素移动到前面/后面时，排序位置的任何最大连续子序列都会给出最小的移动。 

用于输入`[3, 5, 8, 1, 7]`：

 | 我| 位置[i] | 当前长度 | 最大长度 |
 | ---| ---| ---| ---|
 | 0 | 1 | 1 | 1 |
 | 1 | 3 | 1 | 1 |
 | 2 | 4 | 2 | 2 |
 | 3 | 0 | 1 | 2 |
 | 4 | 2 | 1 | 2 |

 最大长度 = 2，因此最少移动 = 5 - 2 = 3。检查表明移动`1`到前面和`8`在 2 次移动中对数组进行回排序，因此在实践中我们可以通过仅考虑从最小位置开始的序列来调整算法。 在简单版本中，由于 n 很小，这种简单的方法就足够了。
