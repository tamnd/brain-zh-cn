 ## 解决方案
 ## 问题理解

 我们有几个独立的数组。 对于每个数组，我们可以重复收缩元素，其中一个操作选择一个位置并将其值替换为向下舍入的一半。 不允许交换，因此元素的顺序是固定的。 

目标是应用最少数量的此类收缩操作，以便在所有修改之后，数组变得从左到右严格增加。 如果无论我们如何收缩元素都无法实现严格增加，我们必须报告不可能。 

一个关键的结构点是每个元素只能沿着通过重复整数除以二获得的值链向下移动。 每个数字都有一个短的“价值轨迹”，因为在给定的约束条件下，重复减半至多大约 31 步即可达到零。 

每个测试用例的约束非常小，最多有 30 个元素。 这立即排除了对复杂数据结构或全局优化的任何需要。 然而，测试用例的数量很大，因此每个测试用例的解决方案必须是线性的或接近线性的。 

这里经常失败的一个天真的误解是贪婪地独立地将每个元素缩小到仅大于先前的结果，而不考虑未来的后果。 这可能会失败，因为将当前元素设置得太小可能会迫使下一个元素进入不可能的位置，即使稍大的选择会起作用。 

另一种失败模式来自于仅在必要时减少。 有时，我们必须积极地将早期元素减少为后来元素的“自由空间”，即使当前元素已经满足局部严格的不平等。 

## 方法

 蛮力的想法是将每个元素视为具有通过重复除以二获得的一小组可能值。 我们可以在数组中尝试这些选择的所有组合，并检查哪些序列严格递增，并沿途计算操作。 由于每个元素最多有 31 个状态，这导致大约$31^n$的组合，即使对于$n = 30$，因为它呈指数爆炸。 

关键的观察是，一旦我们从左到右处理数组，决策就是局部的。 当我们确定位置值时$i$，它对未来元素的唯一要求是下界：下一个元素必须严格大于它。 因此，对于每个元素，我们只需要选择通过减半所能达到的最小可能值，该值仍然严格大于先前选择的值。 

然而，有一个重要的转折：我们不仅仅是选择值，我们还要付出等于减半操作次数的成本。 因此，在所有有效的变换值中，我们需要一个在最小化运算的同时满足不等式的值。 

这导致了贪婪的构造：对于每个位置，我们枚举从原始数字可达的所有可能值，将每个值与所需的除法数量配对，并在前一个元素施加的约束下选择最佳可行的值。 

由于每个数字只能减半 30 次左右，因此枚举每个元素的所有状态的成本很低。 贪心选择之所以有效，是因为一旦我们确定了位置的值$i$，任何超出需要的选择只会使未来的约束变得更困难，而不是更容易，而且也不会降低未来的成本。

 ## 算法演练

 我们从左到右处理数组，同时保留最后选择的值。 

1. 对于每个元素$a_i$，我们生成所有可达对$(v, c)$， 在哪里$v$是重复除以 2 所得的值$c$是达到该目标所需的操作数。 这是通过重复除法直到达到零来完成的。 这个枚举很便宜，因为深度最多为 31。 
2.我们尝试选择一个值$v$对于当前位置，使得$v > \text{prev}$， 在哪里`prev`是为前一个元素选择的值。 
3. 在所有有效的$v$，我们选择成本最小的一个$c$。 如果多个值共享相同的成本，我们更喜欢较小的值$v$。 这种偏好有助于使未来的约束变得更容易，因为较小的值在它们上面留下了更多的空间。 
4. 如果没有可达值满足$v > \text{prev}$，我们得出结论，不可能建立一个严格递增的序列并立即停止。 
5. 选择最佳配对后，我们更新`prev = v`并积累成本。 

核心推理是，在每一步中，我们都将所有未来的可能性压缩为单个约束值。 唯一保留的信息是仍然保留可行性的最小可能阈值。 

### 为什么它有效

 正确性取决于每个元素的可达值形成单调递减链的事实。 职位任意选择$i$只通过它设置的阈值影响未来的元素。 如果我们选择一个可行的值$a_i$，选择较大的只能减少有效选项的数量$a_{i+1}$，永远不会增加它们，同时也不会改善其成本结构。 因此，当地最便宜的可行值始终是安全的。 

因为状态空间每个元素都是线性的，并且我们从不重新审视决策，所以不需要回溯。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def get_states(x):
    states = []
    steps = 0
    while True:
        states.append((x, steps))
        if x == 0:
            break
        x //= 2
        steps += 1
    return states

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    prev = -1
    ans = 0
    possible = True

    for i in range(n):
        states = get_states(a[i])

        best_cost = float('inf')
        best_val = None

        for v, c in states:
            if v > prev:
                if c < best_cost or (c == best_cost and (best_val is None or v < best_val)):
                    best_cost = c
                    best_val = v

        if best_val is None:
            possible = False
            break

        ans += best_cost
        prev = best_val

    print(ans if possible else -1)
```功能`get_states`显式构造每个数字的完整减半链。 这是安全的，因为链长度受整数位数的限制。 

在主循环内，我们维护`prev`，最后选择的值。 对于每个新元素，我们扫描其所有可达状态并选择最便宜的有效状态。 价值上的平局确保我们不会不必要地提高下一步的门槛。 

一个微妙的实现细节是初始化`prev`为严格小于任何可能的数组值的值。 使用`-1`就足够了，因为转换后的所有值都是非负的。 另一个重要的细节是当位置没有有效状态时立即中断，因为后面的元素无法修复已经中断的严格递增条件。

 ## 边缘情况

 一种微妙的情况是价值提前崩溃到零。 例如，`[2, 1]`强制第二个元素严格大于第一个元素，但第一个元素只能向下，不能向上，所以我们必须确保我们不会错误地接受`0 > 0`风格平等。 该算法处理这个问题是因为我们总是强制执行`v > prev`， 不是`>=`。 

当较大的初始值看起来更糟糕但实际上保留了未来的可行性时，就会出现另一种边缘情况。 例如，选择`1`早期可能会阻止后来的元素，同时选择`2`稍微高一点的成本可以实现完整的序列。 所有可达状态之间的贪婪选择确保我们在提交之前始终考虑所有此类替代方案。 

最后，具有多个零的数组测试不可能性检测。 一次`prev`变成`0`，后面的元素不能减少到低于或等于它，因此只有严格的正可达值才重要。 如果不存在，我们正确地终止`-1`。
