 ## 解决方案
 ## 问题理解

 该数组代表放在一排盘子上的一堆煎饼。 你可以重复选择一个煎饼并将其移动一步到相邻的盘子，每次移动支付一个成本。 经过足够的操作后，您希望生成的配置从左到右不增加，这意味着每道菜的煎饼数量至少与其右侧的菜肴一样多。 

煎饼的总数是固定的，但它们的分布可以任意改变，只要每次移动仅将一个煎饼移动到相邻位置即可。 目标不是达到特定的目标排列，而是达到满足单调性条件同时最小化相邻移动总数的任何排列。 

约束足够小，二次或三次动态规划解决方案是可以接受的。 当 n 和 m 达到 250 时，O(n·m²) 或 O(n·m³) 方法在 2 秒限制下是可行的，但任何试图直接模拟运动或枚举所有配置的方法都是不可能的，因为分布的状态空间呈指数增长。 

天真的直觉可能会建议，每当出现违规行为时，就会贪婪地将煎饼从左推到右。 但这会失败，因为局部修复可能会增加未来的成本。 例如，像 [0, 0, 10, 0, 0] 这样的配置可能看起来很容易贪婪地平滑，但任何关于在哪里铺煎饼的早期决定都会影响以后的全局移动成本，因为每次移动都会累积距离。 

当贪婪地均衡相邻值时，会出现另一个微妙的失败情况。 如果您采用 [3, 0, 3]，贪婪修复可能会立即将煎饼从第三道菜移动到第二道菜，但根据后面的结构，最好从左侧重新分配。 关键问题是成本取决于行驶的距离，而不仅仅是最终的计数。 

这是最终阵列形状约束下的全局传输优化问题。 

## 方法

 如果我们忽略单调性约束，问题就变成了一条经典的最小成本流：我们将供给 a[i] 与需求 b[i] 匹配，成本就是煎饼行进的总距离。 这相当于对绝对前缀不平衡求和，因为每次我们将煎饼移过边缘时，它都会改变前缀和。 

困难完全来自于最终数组必须是非递增的要求。 该约束耦合了所有位置：选择 b[i] 会限制后面的所有 b[i+1]、b[i+2] 等。 

暴力方法将枚举所有非递增序列 b 的总和 m，计算从 a 到 b 的运输成本，并取最小值。 这种序列的数量是有界长度的分区的数量，即使 m = 250，这个数量也是巨大的，这使得这是不可行的。 

关键的观察是，虽然 b 必须是全局不增的，但它的构造是顺序的。 当我们固定b[i]时，只需保证它不超过b[i−1]即可。 这将问题变成了从左到右的DP，其中国家需要记住两条信息：我们在当前位置分配了多少煎饼，以及迄今为止在供需之间造成的不平衡。 

不平衡可以作为前缀和差来跟踪。 如果 S[i] 是原始数组和目标数组之间直至 i 的累积差异，则每个不平衡单位都会为其持续的每一步贡献成本 1。 这将移动成本转换为绝对前缀和的总和。 

因此，我们不是模拟运动，而是选择一个有效的目标序列，并测量构建前缀时前缀的“不稳定”程度。 对位置、最后选择的高度和当前不平衡进行动态编程可以捕获可行性和成本。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有非递增数组进行暴力破解 | 指数| 指数| 太慢了|
 | DP 位置、最后值和前缀不平衡 | O(n·m²·m) | O(m²·米) | 已接受 |

 ## 算法演练

 我们定义一个从左到右构建目标数组的 DP。 

1. 我们将最终的数组解释为序列 b，其中 b[i] 是分配给第 i 道菜的煎饼数量。 约束是 b[i] ≥ b[i+1]，因此当我们向右移动时，序列永远不会增加。 
2.我们定义一个前缀不平衡S，它跟踪与我们分配的相比，我们还有多少“正在运动”的煎饼。 形式上，处理 i 个位置后，S 等于总计 a[1..i] 减去总计 b[1..i]。 这种不平衡决定了成本，因为每一单位的不平衡都会为每一步贡献一个单位的成本，因此贡献 |S| 每个前缀的答案。 
3.我们定义一个DP状态dp[i][x][s]，意思是处理完前i个菜后，最后选择的值是x，当前的不平衡度是s。 最后一个值是必需的，因为序列必须保持不递增，因此下一个值最多为 x。 
4. 在每个位置 i，我们尝试 b[i] 的所有可能选择，从 0 到前一个值 x。 这确保了单调性得以保留。 
5. 对于 b[i] 的每个选择，我们将不平衡更新为 s + a[i] − b[i]。 成本增加了新不平衡的绝对值，因为这是在此前缀处累积的成本。 
6. 处理完所有位置后，我们对所有可能的最后值 x 取最小值 dp[n][x][0]，因为最终的不平衡必须为零才能保留煎饼总数。 

### 为什么它有效

 关键的不变量是，处理 i 个位置后，每个有效的移动序列都对应于一个状态（i，最后选择的值，前缀不平衡）。 不平衡完全捕获了截至该点的所有移动成本，与未来的决策无关，而最后选择的值编码了影响未来可行性的唯一约束。 因为任何有效的非递增序列都可以增量地构建，而无需超出此约束，因此 DP 可以探索整个可行空间，而不会重复或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    OFFSET = m
    INF = 10**18

    dp = [[[INF] * (2 * m + 1) for _ in range(m + 1)] for _ in range(2)]
    
    for v in range(m + 1):
        dp[0][v][OFFSET] = 0

    cur, nxt = 0, 1

    for i in range(n):
        for v in range(m + 1):
            for s in range(2 * m + 1):
                dp[nxt][v][s] = INF

        for last in range(m + 1):
            for s in range(2 * m + 1):
                if dp[cur][last][s] == INF:
                    continue
                cur_cost = dp[cur][last][s]

                for b in range(last + 1):
                    ns = s + a[i] - b
                    if 0 <= ns <= 2 * m:
                        val = cur_cost + abs(ns - OFFSET)
                        if val < dp[nxt][b][ns]:
                            dp[nxt][b][ns] = val

        cur, nxt = nxt, cur

    ans = INF
    for last in range(m + 1):
        ans = min(ans, min(dp[cur][last][OFFSET]))

    print(ans)

if __name__ == "__main__":
    solve()
```该实现使用位置上的滚动 DP 来保持内存稳定。 最后选择的高度在外部状态中迭代，并且不平衡性被移动偏移量，因此可以将其存储在数组中。 每次转换都通过将下一个高度限制为最多前一个高度来强制执行非增加约束。 

成本更新使用前缀不平衡的绝对值，这对应于有多少煎饼实际上在该前缀边界“不合适”。

 ## 边缘情况

 当所有煎饼都集中在一个位置时，就会出现一种极端情况。 DP 通过允许较大的暂时不平衡来处理此问题，但最终强制其恢复为零。 累积的成本等于这些煎饼必须行进的总距离，这正是绝对前缀和捕获的内容。 

另一个微妙的情况是，最佳解决方案需要暂时增加局部不平衡，然后再减少。 由于DP除了通过成本之外不会约束中间不平衡，因此它自然允许这种行为并正确评估其长期成本影响。 

最后一种情况是最优 b 序列具有较长的相等值。 DP 正确地处理了这个问题，因为转换允许 b[i] 保持等于 b[i−1]，这会创建平坦区域，而不会强制进行不必要的重新分配。
