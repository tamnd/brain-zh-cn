 ## 解决方案
 ## 问题理解

 我们观察到一系列访客依次进入一个房间。 他们中的一个人在某个时刻偷了一幅画，但我们不知道偷窃发生在什么时候。 每个参观者都会报告他们在进入时是否看到了这幅画，或者他们不记得了，或者他们给出了一个武断的答案，如果他们是小偷。 

关键结构是所有诚实的人要么说实话，要么回答“我不记得了”。 只有小偷可以任意撒谎，这意味着我们可以自由地重新解释他们的答案以使场景保持一致。 

任务是计算序列中有多少个位置可能是小偷，前提是至少存在一个对答案的一致解释。 

测试用例的总长度限制非常大，因此任何解决方案都必须在每个测试用例的线性时间内处理每个字符。 这排除了任何二次推理，例如尝试每个候选窃贼并通过每次扫描整个字符串来验证一致性。 

当字符串不包含任何信息（例如所有问号）时，会出现微妙的边缘情况。 在这种情况下，每个人都可以像小偷一样保持一致，因为我们总是可以分配避免矛盾的真值。 另一种边缘情况是完全确定性的字符串，例如全零或全一，其中根据前缀约束的一致性，通常只有一个或两个位置保持可行。 

## 方法

 一个蛮力的想法是假设每个人都是小偷并模拟我们是否可以为所有其他人分配一致的真值。 对于固定的候选者，我们需要重建这幅画是否出现在每个人面前，确保每个声明的“0”或“1”都与该重建兼容，除了可能出现在小偷身上的情况。 这种模拟会花费每个候选者的线性时间，导致整体复杂度呈二次方，这对于输入大小来说太慢了。 

关键的观察结果是问题的结构是基于前缀的。 在序列中的任何一点，约束系统仅取决于我们看到强制绘画在某个索引之前仍然存在或不存在的语句的次数。 一旦我们正确地解释了这个过程，一致性条件就会分解为跟踪候选分裂点是否可以将“真理执行”约束与“未知导致的自由”分开。 

这将问题简化为针对每个位置检查该位置之前的前缀及其之后的后缀是否都可以与该绘画存在的至少一个有效时间线保持一致。 这可以使用前缀和后缀聚合在线性时间内维护。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个候选人的暴力模拟| O(n²) | O(1) | O(1) | 太慢了|
 | 前缀后缀可行性计数 | O(n) | O(n) 或 O(1) | 已接受 |

 ## 算法演练

 我们将问题重新解释为维持假设的盗窃点是否将序列分为前缀（绘画在入口处必须仍然存在）和后缀（绘画可能已经消失）。

1.预先计算前缀信息，描述如果绘画最初仍然存在，则直到i的前缀是否可以一致。 这是通过跟踪我们是否强制要求的“1”和“0”类型答案之间存在矛盾来完成的。 
2.预先计算后缀信息，描述如果绘画在进入该段之前已经消失，则描述从i开始的后缀是否可以一致。 这再次简化为检查是否没有强制陈述与绘画的缺失相矛盾。 
3. 对于每个位置 i，将其解释为潜在的小偷。 假设那些朋友进来时画仍然存在，i前面的前缀必须一致。 在假设这幅画可能已经消失的情况下，i后面的后缀必须保持一致。 
4. 计算前缀和后缀约束同时成立的所有索引 i。 这些指数代表所有可能成为小偷的人，同时保留对所有答案的至少一种有效解释。 
5. 返回此计数。 

关键的简化是，所有内部一致性约束在每个位置上都分解为两个独立的布尔条件，因为小偷的唯一作用是从系统中删除一个冲突的约束。 

### 为什么它有效

 每个有效的场景都有一个独特的绘画消失的最早时刻。 那一刻之前的一切都必须与绘画的存在相一致，之后的一切都必须与它的消失相一致。 选择窃贼有效地决定了我们可以在哪里打破一致性。 由于只允许有一个中断，因此可行性降低为检查删除该单点是否可以解决所有矛盾。 前缀和后缀计算准确地捕获每个候选位置是否存在这样的单个断点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)

        left_ok = [True] * (n + 1)
        right_ok = [True] * (n + 2)

        # prefix check: assume painting exists initially
        seen_bad = False
        for i in range(n):
            if s[i] == '0':
                seen_bad = True
            # prefix i is valid if no contradiction accumulated
            left_ok[i + 1] = not seen_bad

        # suffix check: assume painting already gone
        seen_good = False
        for i in range(n - 1, -1, -1):
            if s[i] == '1':
                seen_good = True
            right_ok[i + 1] = not seen_good

        ans = 0
        for i in range(n):
            if left_ok[i] and right_ok[i + 2]:
                ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案将字符串分为两种机制的可行性。 向前扫描追踪我们是否遇到任何如果这幅画仍然存在就不可能出现的陈述。 假设这幅画已经消失，向后扫描也会做同样的事情。 如果每个候选指数可以充当这些制度之间的单一过渡点，那么它就是有效的。 

一个常见的陷阱是试图对每个索引进行本地推理，而没有意识到只允许一个全局更改。 前缀和后缀结构确保我们只计算可以作为单个全局更改的位置。 

## 工作示例

 考虑输入`1110000`。 前缀扫描不会发现任何矛盾，直到我们开始遇到零，之后恒定存在的假设就被打破了。 一旦出现在后缀区域中，后缀扫描就会对称地过滤可行性。 只有两个分割点能够在这两个约束下幸存下来，这与只有两个位置可以充当小偷的事实相匹配。 

为了`?????`，两次扫描都没有发现矛盾，因为未知数永远不会强制执行约束。 因此，每个位置都可以作为断点。

 ## 边缘情况

 当字符串统一时，例如所有问号，前缀和后缀约束在任何地方都保持有效，因此每个索引都会被计算在内。 当字符串在 0 和 1 之间紧密交替时，前缀条件很快就会失败，将有效范围压缩为一个小子集。 当字符串长度为一时，两次扫描都会简单地接受该单个位置作为唯一可能的窃贼，因为不会形成矛盾。
