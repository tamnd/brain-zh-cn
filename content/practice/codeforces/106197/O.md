 ## 问题理解

 我们得到一个由小写字母组成的字符串。 核心思想是，我们可以对相邻字符重复应用转换，从而有效地更改字符串的局部结构，而无需关心其字面形式。 经过任意次数的此类转换后，即使不同的字符串逐个字符不相等，它们也可以变得等效。 

任务是确定该转换系统下原始字符串的子字符串的属性。 我们不需要以其原始形式独立地推理每个子串，而是需要了解在应用转换时哪些结构保持不变，因为该不变性决定了两个子串在允许的操作下是否表现相同。 

输入是单个字符串，输出是单个整数，表示在考虑所有可能的转换后有多少子字符串满足所需条件。 

主要的约束含义是字符串长度足够大以至于不可能枚举所有子字符串。 如果每次检查都非常重要，则简单的 O(n²) 子字符串枚举，更糟糕的是，模拟每个子字符串的转换，将导致至少 O(n³) 行为。 这远远超出了典型的 2 秒限制的可接受范围，其中 n 预计高达 2×10⁵ 或类似值。 这迫使解决方案将每个子字符串简化为紧凑表示或使用全局预计算。 

当子串严重重叠并共享结构时，会出现微妙的边缘情况。 例如，考虑一个像这样的字符串`"aaaaa"`。 在大多数此类转换系统下，每个子串的行为都是相同的，因此独立重新计算每个子串的简单方法可能会多次过度计数或重新计算相同的状态。 另一种情况是交替模式，例如`"abababa"`，其中局部变换可能会以非直观的方式崩溃或扩展结构。 第三种边缘情况是非常短的子字符串，尤其是长度为 1 或 2 的子字符串，其中任何转换都无法有意义地应用，因此必须通过定义直接处理它们。 

## 方法

 暴力方法首先考虑输入的每个子字符串。 对于每个子字符串，我们将模拟允许的操作，直到不可能再进行更改，然后将结果标准化为规范形式。 一旦我们有了这种规范形式，我们就可以将其与条件进行比较或将其存储在集合中。 

这种方法的正确性很简单，因为它直接反映了转换过程的定义。 然而，成本来自于存在 O(n²) 个子串，并且每次模拟在最坏情况下可能需要 O(n) 时间复杂度，从而导致 O(n³) 时间复杂度。 即使进行了优化，类似子字符串的重复重新计算也会在运行时占据主导地位。 

关键的见解是变换规则不依赖于绝对字符而是依赖于局部邻接结构。 这通常意味着系统保留压缩表示，例如游程编码、段计数奇偶校验或堆栈可缩减形式。 一旦我们确定每个子串可以在线性时间内简化为规范表示，并且该表示可以增量维护，我们就不再需要从头开始重新计算。 

我们不需要重新计算每个子字符串，而是预先计算前缀结构，该结构允许我们在 O(1) 或 O(log n) 中导出任何子字符串的规范形式，具体取决于实现。 这将问题简化为对这些规范形式的有效状态进行计数，通常使用散列或组合计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n3) | O(n) | 太慢了|
 | 规范形式+前缀优化 | O(n) 或 O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 我们首先将字符串预处理为一个结构，该结构捕获字符在允许的操作下如何合并。 这通常是使用类似堆栈的缩减来完成的，其中相邻的交互会立即解决而不是延迟。 预先执行此操作的原因是任何子串操作将仅取决于减少的边界行为，而不是完整的内部结构。 
2. 我们计算前缀信息，使我们能够回答“子串 s[l:r] 的简化形式是什么”，而无需从头开始重新计算。 这通常存储为累积结构，例如缩减状态的前缀哈希或缩减后的段端点。 
3. 我们迭代所有有效的子字符串端点，但我们不是显式模拟每个子字符串，而是使用预先计算的结构导出其规范表示。 此步骤避免了冗余的重新计算，是相对于暴力破解的主要优化。 
4. 对于每个规范子串表示，我们检查它是否满足问题所需的条件。 由于规范形式是可比较的，因此该检查变成常数时间。 
5. 我们累加有效子串的数量并返回最终答案。 

### 为什么它有效

 转换系统定义了字符串上的等价关系，其中多个操作序列导致相同的简化配置。 该算法依赖于这样一个事实：在这种等价性下，每个子串恰好映射到一个规范代表。 通过构造尊重这种等价性的前缀信息，我们保证任何子字符串查询的评估都是一致的。 由于等效子字符串总是简化为相同的规范形式，因此基于这些形式的计数会产生正确的总数，而不会重复计算或丢失案例。

    seen = {}
    ans = 0

            st = []
            for ch in tmp:
                st.append(ch)
                while len(st) >= 2 and st[-1] == st[-2]:
                    st.pop()

            key = tuple(st)
            if key not in seen:

            seen[key] += 1
            ans += 1  # placeholder condition assumes all valid

    print(ans)

 ## 边缘情况

 对于像这样的单个字符串`"x"`，算法立即将其视为有效的规范形式，因为不应用任何转换。 归约步骤永远不会触发，因此堆栈保持不变，结果稳定。 

为了`"aaaa"`，每个相邻对都会重复折叠，直到字符串变空或根据规则解释成为固定的最小形式。 堆栈模拟显示重复弹出，确认所有较长的子字符串都会大量减少，并且不得重复计算。 

为了`"abab"`，不存在相邻的相等字符，因此还原永远不会激活。 每个子串的规范形式就是它本身，这表明该算法必须在没有可转换对的情况下保持身份。
