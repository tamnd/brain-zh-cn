 ## 问题理解

 我们给出了一个网格问题，它的行为不太像着色任务，而更像隐藏在网格内的图上的定向传播系统。 

的每个单元格$n \times n$grid 包含一个方向，水平或垂直。 从任何选定的单元格中，我们执行取决于其方向的操作：如果单元格指示水平，我们激活其整个行，如果它指示垂直，我们激活其整个列。 目标是选择一系列单元格，以便网格中的每个单元格至少被激活一次，并且我们希望最大限度地减少我们做出的此类选择的数量。 

重新表述这一点的一个有用方法是，每个操作选择一个节点，并且该节点根据其类型“覆盖”其行中的所有节点或其列中的所有节点。 任务是确保全覆盖$n^2$使用尽可能少的选择的节点。 

输入大小约束在这里很重要：所有测试用例的总网格面积最多约为$10^3$，每个网格最多$1000 \times 1000$。 这立即排除了任何二次方$n^2$，因为那已经是$10^6$每个测试用例，并且在跨用例相乘时太慢。 甚至$O(n^3)$的方法是不可行的。 解决方案本质上必须检查网格恒定次数，并贪婪地或通过结构分解来构建答案。 

往往会打破天真的推理的关键边缘情况是，局部贪婪选择似乎减少了未覆盖的单元，但实际上会在以后强制进行额外的操作。 例如，如果通过垂直选择几乎可以完全覆盖一行，但有一个单元格未对齐，则贪婪求解器可能会选择一种提前“修复”该行的操作，然后陷入需要额外列操作的困境。 

一个小例子可以说明这一点：```
n = 2
VH
HV
```天真的贪婪方法可能会选择 (1,1)，认为它对第 1 行和第 1 列都有帮助，然后选择 (2,2)，但根据覆盖方向的解释，您可能最终会过度计数或错过单个操作的最佳重用。 正确答案是 2，但是许多贪婪变体通过独立处理行和列决策而不是作为耦合结构来错误地生成 3。 

更深层次的问题是，每个细胞不仅是一个目标，而且是“覆盖方向”的选择，并且这些方向在全球范围内相互作用。 

## 方法

 蛮力的想法很简单：将每个单元视为一个可能的操作并模拟所有操作子集。 每个子集定义一组被激活的行或列，我们检查它们的并集是否覆盖整个网格。 这是正确的，因为它详尽地探索了所有可能的选择。 

然而，状态空间是$2^{n^2}$，甚至对于$n = 10$，这已经是一个天文数字了。 甚至限制为精确选择$k$操作仍然导致$\binom{n^2}{k}$，这是无法管理的。 

关键的结构观察是网格分解为两个独立的覆盖系统：水平单元引起的行覆盖和垂直单元引起的列覆盖。 每个操作都只对一个覆盖轴做出贡献，这意味着问题相当于确保每一行和每一列都以至少一种兼容的方式“触及”。 一旦看到这一点，网格就不再是二维对象，而是成为行和列之间的双向交互。 

我们不再考虑覆盖单元格，而是转向确保每一行或每一列至少有一个有效的“激活单元格”。 这将问题转化为选择一组最小的代表性激活，可以贪婪地构造它，因为一旦我们确保方向的一致性，每行或列都可以独立满足。

 ## 算法演练

 该构造依赖于扫描网格并决定以受控方式“致力于”覆盖行或列的操作。 

1. 我们首先根据每个单元格是否有助于行覆盖或列覆盖来对它进行分类。 水平单元格被视为可以激活其行的候选单元，垂直单元格被视为可以激活其列的单元格。 这种分离是必要的，因为每个操作都有固定的影响方向。 
2. 然后我们跟踪哪些行和列仍然需要覆盖。 最初，所有行和列都未被覆盖，因为尚未执行任何操作。 
3.我们迭代网格，每当我们遇到一个方向可以覆盖未覆盖结构的单元格时，我们就选择它作为操作。 如果它是水平的，我们将其行标记为被覆盖； 如果是垂直的，我们将其列标记为被覆盖。 
4. 选择一个操作后，我们立即在概念上传播其效果，这意味着我们不会显式更新该行或列中的所有单元格。 相反，我们维护所覆盖的行和列的簿记集。 
5. 我们继续此过程，直到以保证间接到达所有单元格的方式覆盖每一行或每一列。 

关键思想是我们永远不会重新访问已经满足的结构，这可以防止冗余操作。 

### 为什么它有效

 不变的是，在任何时候，每个未覆盖的行或列仍然至少有一个候选单元格可以满足它，而不与之前的选择发生冲突。 每个操作都会从系统中删除一个自由度（一行或一列），并且永远不会重新引入它的需要。 因为行和列形成了一个二分覆盖系统，一旦提交就没有依赖循环，所以贪婪选择不会让我们陷入以后需要额外操作的困境。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [input().strip() for _ in range(n)]

    row_used = [False] * n
    col_used = [False] * n
    ops = []

    for i in range(n):
        for j in range(n):
            if g[i][j] == 'H':
                if not row_used[i]:
                    row_used[i] = True
                    ops.append((i + 1, j + 1))
            else:
                if not col_used[j]:
                    col_used[j] = True
                    ops.append((i + 1, j + 1))

    print(len(ops))
    for x, y in ops:
        print(x, y)

if __name__ == "__main__":
    solve()
```该实现依赖于每行和每列仅需要单个触发操作的事实。 布尔数组可防止重复选择相同的结构要求。 

最微妙的部分是避免过度选择：没有`row_used`和`col_used`，该算法会在每行或每列选择多个单元格，从而在不提高覆盖范围的情况下夸大答案。 

索引是另一个常见的错误来源。 输出是从 1 开始的，而内部处理是从 0 开始的，因此每个坐标在发射时必须一致地调整。

 ## 边缘情况

 当行和列以相互冲突的方向重复出现时，就会出现极端情况。 该算法仍然可以正确处理此问题，因为它从不尝试“解决”冲突，它只记录每行或列的第一个成功触发。 即使一行包含许多水平单元格，也只需要一个，后续的单元格将被忽略。 

另一种边缘情况是网格完全由垂直或完全由水平单元填充。 在仅垂直的情况下，每一列都只进行一次操作，类似地，对于仅水平的网格，每行都被覆盖一次。 该算法不会过度计数，因为每个结构单元在第一次激活后立即被标记为已使用。 

最后一种情况是棋盘图案，其中每个单元格交替方向。 该算法在行触发器和列触发器之间交替，但是`used`阵列确保没有行或列被激活两次，从而防止操作中的二次爆炸。
