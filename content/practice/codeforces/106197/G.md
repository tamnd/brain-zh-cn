 ## 解决方案
 ## 问题理解

 我们为每个测试用例提供一个十进制字符串，并要求我们查看通过删除其中一些数字同时保留顺序而可以形成的所有整数。 每个这样的派生数字在数字意义上都是原始数字的子序列。 从这个可达数字的集合中，我们计算 mex，这意味着在解释为数字时永远不会作为这些子序列之一出现的最小非负整数。 

核心对象不是字符串本身，而是可以由它形成的整数集。 例如，如果字符串包含单个数字“7”，则唯一的子序列是空选择和“7”。 如果它包含多个数字，则子序列包括所有递增索引选择，这会快速创建许多重复的数值，但仍然只有有限多个不同的整数。 

这些限制意味着输入的数字长度可能非常大，所有测试用例最多可达二十万位。 这排除了任何尝试显式枚举子序列的方法。 即使存储所有子序列也是不可能的，因为长度为 n 的字符串有 2^n 个子序列，甚至适度的 n 也会使指数爆炸变得不可行。 

关键的微妙之处在于子序列不受连续性的限制，因此数字的存在比结构更重要。 如果数字 k 存在于字符串中的某个位置，则它只能作为长度为 1 的子序列出现。 像 10 或 123 这样的数字取决于数字的相对顺序和可用性，而不仅仅是频率。 

一个幼稚的错误来自于将其视为组合子序列计数问题而不是数字模式的可达性问题。 例如，如果假设数字 {0,1,2} 保证所有排列，那么这是错误的，因为子序列保留顺序，因此除非数字以确切的相对顺序出现，否则无法形成“210”。 

第二个常见的失败案例是忽略了多位数取决于位置约束。 例如，即使存在数字 1 和 0，也不能保证数字 10，除非“1”出现在“0”之前。 

该问题从根本上讲是确定哪些整数可以形成为子序列，然后找到第一个无法形成的整数。 

## 方法

 一个蛮力的想法是生成所有子序列，将每个子序列转换为整数，并将它们插入到一个集合中，然后从 0 向上扫描，直到找到缺失值。 这在原则上是正确的，因为它显式地构造了完整的可达集。 问题在于规模。 即使对于 50 位数字的字符串，子序列的可能性也已经超过 10^15，并且将每个序列转换为整数会增加开销。 瓶颈是指数代。 

关键的观察是我们实际上并不需要完整的子序列集。 我们只关心小整数是否作为子序列存在。 这完全改变了观点。 我们不是枚举所有子序列，而是问：使得 k 不能形成子序列的最小 k 是多少？ 

这将问题转化为对整数升序进行建设性检查。 对于每个候选整数x，我们需要测试x是否可以作为数字字符串内的子序列进行匹配。 这是标准的贪婪扫描：我们遍历字符串并尝试按顺序匹配 x 的数字。 如果我们完成，x 是可以实现的； 否则就不是。 

关键的结构见解是，如果从 0 到 M-1 的所有整数都是可实现的，那么 mex 就是 M，所以我们可以在第一次失败时立即停止。 我们不需要超越这一点。

效率的提高来自于限制我们需要检查的距离。 如果字符串很长，它往往会很快包含所有小数字模式，但最终某些数字将由于排序限制而失败。 每次检查在字符串长度上都是线性的，并且检查的数量通常很小，因为 mex 相对于数字限制增长缓慢。 

| Approach | 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解子序列 | O(2^n) | O(2^n) | O(2^n) | O(2^n) | 太慢了|
 | 增量后续检查 | O(M·n) 其中 M 是 mex | O(1) 额外 | 已接受 |

 ## 算法演练

 1. 将数字转换为数字字符串。 这允许通过指针扫描而不是算术分解来处理子序列匹配。 
2. 从 x = 0 开始，尝试确定 x 是否可以构成数字串的子序列。 检查是逐位进行的。 
3. 要测试候选 x，请将其转换为其十进制表示形式并使用指针扫描主字符串。 向前移动指针，直到当前数字与 x 的下一个所需数字匹配。 如果 x 的所有数字都匹配，则可以实现 x。 
4. 如果 x 可实现，则增加 x 并重复检查 x + 1。 
5. 当候选x无法匹配时停止。 该值是 mex，因为所有较小的值都被验证是可以实现的。 

这种扫描起作用的原因是，就数字排序约束而言，子序列的可行性是单调的。 如果无法匹配某个数字，则具有相同前缀约束的更大数字无法“修复”缺失的排序。 

### 为什么它有效

 每个整数检查都简化为验证固定模式是否作为数字字符串的子序列出现。 这是一个经典的贪婪匹配问题，其中最早可能的匹配始终是最佳的，因为延迟匹配只会减少未来的选择。 由于我们按升序检查整数，因此在停止之前所有较小的候选者都被确认可达，因此第一个失败正是 mex 定义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can_form(s, target):
    j = 0
    n = len(s)
    for i in range(n):
        if j < len(target) and s[i] == target[j]:
            j += 1
            if j == len(target):
                return True
    return False

def solve():
    s = input().strip()
    x = 0

    while True:
        t = str(x)
        if not can_form(s, t):
            print(x)
            return
        x += 1

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```核心功能是`can_form`，它对数字字符串执行线性扫描，同时跟踪候选号码的进度。 指针`j`确保我们尊重子序列的顺序约束。 

外层循环按递增顺序递增候选值，保证一旦发生故障，我们就找到了最小的不可到达整数。 

一个微妙的实现细节是，在循环内将整数转换为字符串是安全的，因为在典型约束下，实际上 mex 仍然很小，但在最坏的情况下，如果边界更紧，可以通过预先计算表示或使用数字 DP 来优化。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    output = []
    input = _sys.stdin.readline

    def can_form(s, target):
        j = 0
        for c in s:
            if j < len(target) and c == target[j]:
                j += 1
        return j == len(target)

    def solve():
        s = input().strip()
        x = 0
        while True:
            if not can_form(s, str(x)):
                output.append(str(x))
                return
            x += 1

    t = int(input())
    for _ in range(t):
        solve()

    return "\n".join(output)

 ## 边缘情况

 一个关键的边缘情况是数字“0”完全丢失。 在这种情况下，即使许多数字（如 1 或 2）可能是可构造的，mex 也会立即强制为 0。 该算法处理此问题是因为第一次检查 x = 0 在后续扫描中失败。 

另一种情况是数字全部存在但排序会阻止多位数字。 例如，“102”允许1、0、2，但根据位置可能无法形成10。 扫描通过按顺序使用字符来正确强制排序，因此即使所有数字都存在，它也会检测到这些失败。 

最后的边缘情况是像“000000”这样的大量重复。 这里，只能形成由零组成的数字，因此 mex 变为 1。算法首先确认 0，然后在 1 处失败，正确识别由数字多样性而不是长度引起的边界。
