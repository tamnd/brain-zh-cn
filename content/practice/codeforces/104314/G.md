 ## 解决方案
 ## 问题理解

 给定一个由两个整数组成的状态，并且允许我们使用三个可逆操作来转换这对整数。 一个操作从第一个值中减去第二个值，另一个操作将第二个值与第一个值相加，第三个操作交换两个坐标。 任务是确定是否存在将初始对转换为目标对的这些操作的有限序列，如果存在，则输出任何有效的操作序列。 

关键的观点是，我们正在一个无限图上行走，其顶点是整数对。 每个顶点恰好具有与允许的操作相对应的三个出边。 我们被要求提供该图中两个节点之间的可达性，但状态空间在两个方向上都是无界的，因此简单的图搜索立即受到质疑。 

约束允许在开始和目标时数值高达 100000，但中间值可能会变得非常大，并且有一个严格限制，即在任何有效构造期间绝对值必须保持在 10^18 以下。 这是存在构造性或数论结构的强烈暗示，因为在完整状态空间中不受限制的 BFS 或 DFS 是不可能的。 

一些边缘情况值得隔离。 

首先，对称性可以隐藏不可能性。 例如，从 (1, 0) 我们只能达到 (±1, 0) 形式的对，因此尝试达到 (0, 1) 是不可能的，因为交换不会创建非零结构。 

其次，如果两个坐标都为零，则状态是吸收的。 从 (0, 0) 开始，每次操作都会使其保持不变，因此不可能到达任何其他对。 

第三，标志模式很重要。 由于操作是坐标的线性组合，因此出现了某些奇偶性和行列式不变量。 当实际上变换矩阵相对于整数可逆性是奇异的时，朴素的前向模拟可能表明可达性。 

## 方法

 直接的强力方法将尝试从 (a, b) 开始 BFS，在每一步探索所有三个转换。 这原则上是正确的，因为状态图在任何有界区域内都是显式且有限的。 然而，州的数量立即爆炸。 即使将每个维度中的值限制在适度的范围（如 10^6）也会导致巨大的状态空间，并且操作可以轻松地将值推到任何安全 BFS 边界之外。 分支因子为 3，因此在 k 个步骤之后，我们已经有了 3^k 个可能的状态，使得这种方法在达到任何合理的目标大小之前就不可行。 

关键的观察是所有操作都是向量 (m, n) 上的线性变换。 我们可以将它们表示为整数矩阵，行列式为 ±1 或 0，具体取决于解释。 交换是可逆的并保留幅度结构，而加法和减法对应于基本行运算。 这意味着我们正在一个由简单线性变换生成的群体中有效地工作。 

关键的结构见解是，可达对正是那些保留最大公约数的对。 由于加法和减法都保留 gcd(m, n)，并且交换也不会改变它，因此两个数字的 gcd 在所有操作下都是不变的。 这立即给出了一个必要条件：gcd(a, b) 必须等于 gcd(c, d)。 如果失败，则不存在序列。 

一旦gcd匹配，我们就可以逆向思考。 我们不是从 (a, b) 构建 (c, d)，而是尝试使用逆运算将 (c, d) 还原回 (a, b)。 逆结构是等价的，因为交换是其自身的逆，并且加法/减法在符号变化下是对称的。 这使我们能够使用扩展的欧几里得过程构造一个序列：我们在跟踪操作时将一对表示为另一对的整数线性组合。

构造路径源自欧几里得算法。 通过反复从较大的坐标中减去较小的坐标，我们模拟了欧几里德归约。 当坐标与 gcd 结构对齐时，我们可以交换并继续，直到到达目标的基本表示。

 ## 算法演练

 我们使用逆欧几里得约简构造一条从 (c, d) 回到 (a, b) 的路径，然后反转序列。 

1. 首先检查两对是否都是 (0, 0) 或者是否正好有一个是 (0, 0)。 如果一个为零而另一个不为零，则任何操作都无济于事，因为所有变换都保留零向量。 如果两者都为零，则答案为空。 
2. 计算源坐标和目标坐标的 gcd。 如果这些 gcd 值不同，请立即断定不可能。 这是因为每个操作都会保留 gcd。 
3. 从目标对 (c, d) 开始向后工作，重复应用逆欧几里得步骤。 如果 c 和 d 均非零，则比较它们的大小。 如果|c| > |d|，使用重复减法将 c 减少 d 的倍数，这对应于运算 1 或 2 的逆运算，具体取决于符号一致性。 
4.如果|d| > |c|，执行一次交换操作，记为类型3，继续。 这可以保持缩减对称并确保向更小的坐标方向前进。 
5. 继续，直到该对与源匹配直至 gcd 缩放。 由于除非交换，否则每个步骤都会严格减少最大绝对值，因此该过程必须终止。 
6. 以倒序记录操作，然后将其反转以获得正序。 交换仍然是交换，而加法和减法彼此相反。 
7. 输出序列。 

### 为什么它有效

 状态变换保留了由初始对的整数线性组合生成的晶格结构。 每个可达对都位于由 gcd(a, b) 定义的同一格中。 欧几里得算法保证具有相同 gcd 的任意两对可以使用整数行运算相互转换。 交换操作确保我们始终可以选择要减少的坐标，从而防止当一个分量较小但非零时出现停滞。 由于每个归约步骤严格地减少至少一个坐标的大小，因此不可能出现无限循环，并且保证终止。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def gcd(x, y):
    while y:
        x, y = y, x % y
    return abs(x)

def build(a, b, c, d):
    # handle trivial cases
    if (a, b) == (c, d):
        return ""
    if (a == 0 and b == 0) or (c == 0 and d == 0):
        return None

    if gcd(a, b) != gcd(c, d):
        return None

    ops = []
    x, y = c, d

    # reverse-like reduction toward (a, b)
    # we simulate Euclid-style descent
    while (x, y) != (a, b):
        if abs(x) < abs(y):
            x, y = y, x
            ops.append('3')
            continue

        if y == 0:
            break

        # try to reduce x by y
        k = (x - a) // y if y != 0 else 0

        if k == 0:
            # single step reduction
            x = x - y
            ops.append('1')
        else:
            # multiple reductions compressed
            x = x - k * y
            ops.extend('1' * abs(k))

        if len(ops) > 10**6:
            return None

    if (x, y) != (a, b):
        return None

    return ''.join(reversed(ops))

def solve():
    a, b = map(int, input().split())
    c, d = map(int, input().split())

    res = build(a, b, c, d)
    if res is None:
        print("IMPOSSIBLE")
    else:
        print(res)

if __name__ == "__main__":
    solve()
```该实现首先处理出现零向量的退化情况，因为没有操作可以创建或破坏零坐标结构。 gcd 检查强制所有可达状态必须位于同一整数格中的不变量。 

主构造循环尝试模拟从目标对的向后欧几里德下降。 当一个坐标在绝对值中占主导地位时，将应用交换以确保减少始终发生在较大幅度的分量上。 减法步骤直接对应于操作1，为了提高效率，重复的减法被压缩为多个字符。 

最后的反转是必需的，因为我们构建了从目标到源的路径，但必须输出正向变换序列。 长度保护确保我们遵守 10^6 操作限制。

 ## 边缘情况

 当一个坐标在归约过程中变为零时，会出现一种微妙的情况。 例如从(6, 2)开始，重复减法得到(0, 2)。 到那时，只有交换才能恢复进度，因为进一步的减法将会停滞。 该算法通过每当|x|时立即交换来处理这个问题。 < |y|，确保我们永远不会陷入零第一坐标状态。 

另一种情况是当值的符号振荡时。 例如，(5, -3) 可能会在减法过程中翻转符号。 因为运算是线性的，所以符号变化不会影响 gcd 不变性，并且归约仍然收敛于规范形式。 该算法不依赖于符号单调性，仅依赖于每个有效欧几里德步骤之后的幅度减小。
