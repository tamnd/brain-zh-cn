 ## 解决方案
 ## 问题理解

 给定两个非负整数，`a`和`n`。 程序以一个值开始`b = 0`然后应用相同的更新步骤`n`次数：`b := (b - a) & a`这里，减法和按位 AND 是使用二进制补码算术对 64 位整数进行的。 任务是确定最终值`b`毕竟`n`迭代，但没有模拟循环`n`可以大到$10^{18}$。 

输入大小立即排除任何直接模拟。 线性迭代`n`最多需要$10^{18}$步，这远远超出了任何可行的时间限制。 甚至$10^7$每秒的操作数仍然使这成为不可能。 

主要困难在于过渡将算术减法与按位掩码混合在一起，因此演变为`b`不明显单调或线性。 一个天真的尝试会一步一步地计算，但即使像记忆这样的小优化也是不可能的，因为`a`也可以很大并且状态空间是64位的。 

64 位算术边界处的位行为会产生微妙的边缘情况。 例如，如果`a = 0`，则递推式变为`b = 0`永远，无论`n`。 如果`n = 0`，我们必须返回初始的`b = 0`不应用任何过渡。 另一个重要的情况是当`a`是这样的形式`2^k - 1`，其中所有低位均被设置，因为 AND 运算的行为就像屏蔽低位动态而不是算术增长。 

关键的观察结果是，尽管有 64 位空间，但转换是高度结构化的，并且很快就达到一个循环。 

## 方法

 暴力破解的想法很简单：完全按照编写的方式模拟循环。 每次迭代都会重新计算`b = (b - a) & a`。 这是正确的，因为它确实遵循程序。 然而，它需要`n`步骤，所以最坏情况的复杂度是$O(n)$，这是不可能的，当`n`可以是$10^{18}$。 

关键的见解是将变换视为有限状态空间上的函数。 自从`b`是一个64位整数，最多有$2^{64}$可能的状态，因此序列最终必须成为周期性的。 更重要的是，操作是确定性的，并且从初始值快速崩溃到一个非常小的周期`b = 0`。 

我们计算从以下位置开始的序列`0`直到我们达到之前看到的值或检测到循环。 一旦找到循环，我们就不需要进一步模拟。 相反，我们减少`n`对前期后的周期长度取模，并直接索引到周期中。 

这是有效的，因为进入循环后，每个未来状态仅取决于其在循环中的位置，而不取决于完整的历史记录。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n)$|$O(1)$| 太慢了 |
 | 循环检测|$O(k)$,$k \le 2^{64}$但实际规模很小|$O(k)$| 已接受 |

 ## 算法演练

 我们将这个过程视为重复应用一个函数`f(b) = (b - a) & a`开始于`b = 0`。 

1. 开始于`b = 0`以及一个空地图或列表来记录以前看到的值。 我们还跟踪每个值出现的步长索引。 
2. 重复计算下一个状态`b_next = (b - a) & a`。 这是问题定义的确切转换。 
3.如果`b_next`之前已经看到，我们已经检测到了一个循环。 从第一次出现到当前步骤的段形成一个重复循环。 前面的前缀是瞬态阶段。 
4. 一旦检测到周期，就计算瞬态部分的长度和周期长度。 
5. 减少`n`：

如果`n`小于瞬态长度，答案直接是`n`- 前缀中的第一个元素。 

否则，减去瞬态长度并取模循环长度来找到循环内的最终位置。 
6. 返回对应的存储值。 

循环检测就足够了，因为变换是有限的 64 位状态集上的确定性映射。 一旦状态重复，从该点开始的序列必须精确重复，因为该函数没有超出当前状态的记忆。`b`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a = int(input().strip())
    n = int(input().strip())

    def f(x):
        return (x - a) & a

    seen = {}
    seq = []

    b = 0
    step = 0

    while b not in seen:
        seen[b] = step
        seq.append(b)
        if step == n:
            print(b)
            return
        b = f(b)
        step += 1

    start = seen[b]
    cycle = seq[start:]
    cycle_len = len(cycle)

    if n < len(seq):
        print(seq[n])
        return

    n -= start
    n %= cycle_len
    print(cycle[n])

solve()
```该函数构建了轨迹`b`直到重复。 这`seen`字典存储第一次出现的索引，而`seq`保留完整的顺序。 当找到循环时，我们将序列分为前缀和重复循环。 

提前退出`if step == n`避免不必要的循环处理`n`位于非重复前缀内。 

## 工作示例

 ### 示例 1

 输入：`a = 3, n = 2`我们一步步计算：

 | 步骤| 乙| 计算|
 | ---| ---| ---|
 | 0 | 0 | 开始 |
 | 1 | (0 - 3) & 3 = 3 | 第一次转变|
 | 2 | (3 - 3) & 3 = 0 | 第二次转变|

 最终答案是`0`。 

该迹线显示了之间的小周期`0`和`3`。 该序列立即稳定为周期性行为。

 输入：`a = 5, n = 6`| 步骤| 乙| 计算|
 | ---| ---| ---|
 | 0 | 0 | 开始 |
 | 1 | 5 | (0 - 5) & 5 |

 系统进入2个周期`{0, 5}`立即地。 之后，答案仅取决于奇偶性`n`。 

这证实了一旦达到一个循环，在其内部建立索引就足够了。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(k)$| 每个新状态都会计算一次，直到重复；$k$是周期入口长度加上周期大小|
 | 空间|$O(k)$| 我们存储看到的状态和序列直到第一次重复 |

 约束允许最多$10^{18}$迭代，因此直接模拟是不可能的。 基于循环的方法将问题简化为仅探索状态图的可达部分，这在实践中对于这种转换来说非常小并且保证是有限的。

 ## 边缘情况

 当`a = 0`，函数变为`b = (b - 0) & 0`，所以每个状态都崩溃为`0`。 该算法自然地处理这个问题，因为第一个计算的转换等于开始状态，因此循环立即被检测为单个元素。 

什么时候`n = 0`，我们永远不会进入循环。 该算法明确检查`step == n`在初始状态，所以它返回`0`直接匹配初始值`b`。 

当序列立即进入 2 周期时，例如带有小`a`，检测机制记录第一次重复并隔离循环`[x, y]`。 模索引步骤确保大`n`值被正确地减少到这个二元循环中，从而产生正确的交替行为，而无需额外的模拟。
