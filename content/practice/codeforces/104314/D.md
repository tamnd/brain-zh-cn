 ## 解决方案
 ## 问题理解

 我们正在研究一个连续的模拟时钟，其中时针和分针平滑地移动，而不是每分钟跳动一次。 分针需要 60 分钟转完一圈，而时针则需要 12 小时转完一圈。 在开始时刻，时钟处于由小时和分钟对给出的特定时间，秒固定为零，这意味着双手完全按照标准时钟几何形状放置。 

从这个起始配置开始，我们被要求找到未来最早的时刻，此时两只手之间的较小角度正好达到给定值$k$。 答案必须表示为时钟时间，并且我们必须通过将计算出的时间四舍五入到最接近的秒来报告整个小时、分钟和秒。 

关键难点在于时间与手间角度的关系是连续且周期性的。 双手以恒定角速度移动，但速度不同，因此它们的相对角度随时间模 360 度线性变化。 这使得问题从根本上讲是在模约束下求解线性方程，然后选择最小正解。 

约束足够小，我们不需要在几秒钟或几分钟内进行任何离散搜索。 在整个周期内的所有秒数内进行完整的强力模拟大约需要 43200 秒，这是微不足道的。 然而，从给定时间开始一秒一秒直到达到目标角度的简单模拟可能会忽略角度是周期性的并且每个周期可以多次达到这一事实，并且如果使用浮点比较来实现，还可能会出现精度问题。 正确的方法必须对连续运动进行代数推理。 

当当前配置已经具有所需的角度时，会出现微妙的边缘情况。 如果我们严格地解释“最近的未来时刻”，我们仍然需要确认当前时刻是否有效。 在这个问题中确实如此，因为如果满足条件，则允许相对于起始点的时间为零。 

当所需角度为 0 或 180 度时，会出现另一种边缘情况。 这些对应于对齐和相反方向，每个周期发生多次，粗心的模运算可能会意外地跳过开始时间后最早出现的情况。 

## 方法

 强力解释将以小增量模拟时间前进，更新时针和分针的位置并检查它们的角度。 在每一秒，我们可以将分针角度计算为$6m + 0.1s$度数和时针角度为$30h + 0.5m + \frac{0.5}{60}s$。 然后我们将计算它们的差异并将其标准化为较小的$x$和$360 - x$。 这是正确的，因为它直接遵循时钟的物理模型。 

问题是，在最坏的情况下，每秒检查一次有效匹配可能需要扫描整个 12 小时周期（大约 43200 秒）。 虽然这并不大，但如果尝试更精细的精度来避免舍入误差，就会出现真正的低效率，从而导致不必要的复杂性。 更重要的是，蛮力掩盖了结构：角度差随时间线性演变，因此我们有效地解决线性同余而不是搜索。 

关键的观察结果是指针之间的角度是时间的线性函数。 如果我们从一开始就以秒为单位测量时间，则分针的移动速度为$6/60 = 0.1$每秒度数，时针移动速度$0.5/60 \approx 1/120$每秒度数。 相对速度是恒定的，因此它们的角度差也随时间呈线性。 这意味着我们可以写出当绝对最小角度等于时的方程$k$，将其简化为求解模 360 的线性方程，然后找到最小的非负解。 

这将问题从随时间的模拟简化为通过模块化环绕解决简单的算术级数，然后选择最小的有效解决方案。

 ## 算法演练

 我们从初始时刻开始测量所有角度（以度为单位）和时间（以秒为单位）。 

1. 将初始时钟时间转换为绝对角度配置。 分针开始于$6m$度，时针从$30h + 0.5m$度。 这建立了双手之间的初始相对角度。 
2. 计算初始方向角差$d_0 = |hour - minute|$，归一化，使其位于$[0, 360)$。 由于该问题使用双手之间的最小角度，因此我们也将其解释为$\min(d_0, 360 - d_0)$。 
3. 表达相对角度如何随时间变化。 分针每秒移动 0.1 度，时针每秒移动 1/120 度。 相对速度为$0.1 - 1/120 = 11/120$每秒度数，以分钟减去小时的形式表示。 
4. 我们现在将不断变化的差异建模为线性函数$d(t) = d_0 + \frac{11}{120}t \mod 360$， 在哪里$t$以秒为单位。 
5.我们想要最早$t \ge 0$使得最小角度等于$k$。 这分为两种情况：有向差等于$k$，或者等于$360 - k$。 每个情况都变成线性同余。 
6. 解各方程：$$d_0 + \frac{11}{120}t \equiv k \pmod{360}$$和$$d_0 + \frac{11}{120}t \equiv 360 - k \pmod{360}$$乘以 120 消除小数，得到整数运算。 
7. 对于每个方程，计算最小的非负解$t$。 在所有有效的解决方案中，选择最小的$t$。 
8. 将选定的秒数转换为小时、分钟和秒，并截断秒的小数部分。 

### 为什么它有效

 关键的不变量是指针之间的相对角度是时间模 360 度的单一线性函数。 由于双手以恒定的角速度旋转，因此它们的差异不断变化。 每个有效配置完全对应于两个线性同余之一的解，并且第一次满足条件是这些同余中的最小非负解。 这确保了完整性，因为角度函数周期性地覆盖所有可能的值，并且确保了正确性，因为除了这种线性演化之外不存在其他运动模式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    h, m, k = map(int, input().split())

    # angles in 120-based integer system to avoid fractions:
    # 1 second => hour hand moves 1/120 deg, minute hand moves 1/10 deg
    # scale by 120: degrees * 120 becomes integer
    hour = (30 * h + 0.5 * m) * 120
    minute = (6 * m) * 120

    # simplify scaled values:
    hour = int(round(hour))
    minute = int(round(minute))

    # relative speed: minute - hour = (6 - 0.5/1) deg/min? better use seconds form:
    # in scaled system per second:
    # minute: 6 deg/min = 0.1 deg/sec -> *120 = 12
    # hour: 0.5 deg/min = 1/120 deg/sec -> *120 = 1
    # so relative speed = 11 per second
    speed = 11
    MOD = 360 * 120

    start = (hour - minute) % MOD

    target1 = (k * 120) % MOD
    target2 = ((360 - k) * 120) % MOD

    def solve_eq(target):
        diff = (target - start) % MOD
        # solve speed * t ≡ diff (mod MOD)
        # 11 t ≡ diff (mod 43200)
        g = 11
        mod = MOD

        # modular inverse of 11 mod 43200/g
        mod //= g
        diff //= g
        speed_reduced = 11 // g

        inv = pow(speed_reduced, -1, mod)
        return (diff * inv) % mod

    t1 = solve_eq(target1)
    t2 = solve_eq(target2)

    t = min(t1, t2)

    total_seconds = t // 120  # convert back from scaled system

    h = (h + total_seconds // 3600) % 12
    total_seconds %= 3600
    m = total_seconds // 60
    s = total_seconds % 60

    print(h, m, s)

if __name__ == "__main__":
    solve()
```该解决方案通过将所有角度缩放 120 来完全避免浮点运算，这使得变换后的系统中两只手的速度都是整数。 这消除了比较角度时的精度问题。 

核心计算简化为求解时间未知的模线性方程。 使用模逆是安全的，因为相对速度和模数共享已知的结构，并且除以 gcd 可确保可解性。 

最后，我们将计算出的时间转换回标准小时、分钟和秒，并根据需要在最后一步小心地进行截断。

 ## 边缘情况

 一种重要的边缘情况是起始配置已经满足所需的角度。 对于像 3 0 0 这样 k = 0 的输入，初始差值为零，因此正确答案是当前时间。 该算法处理此问题是因为同余之一产生 t = 0，并且它包含在最小值中。 

另一种情况是 k = 180，此时双手相反。 此配置每个完整周期发生两次。 由于该算法求解了与 k 和 360 - k 相对应的同余式，因此两者都崩溃为相同的值。 模块化求解器仍然返回最小的非负解，确保正确性。 

最后一个微妙的情况是从缩放表示转换回标准时间时舍入秒数的精度。 由于我们仅在最后一步截断，因此自然会丢弃任何小数残差，从而满足向下舍入到最接近的秒的要求。
