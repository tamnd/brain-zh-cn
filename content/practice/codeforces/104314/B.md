 ## 解决方案
 ## 问题理解

 我们有一行在空位置和固定比较符号之间交替。 有$N+1$必须用从 1 到 的不同数字填充的位置$N+1$，并且在每两个相邻位置之间恰好有一个约束，“<”或“>”，必须由放置在其旁边的两个数字来满足。 

任务是确定我们是否可以分配大小的排列$N+1$到这些位置，以便每个不平等都成立。 如果可能的话，我们必须输出一个有效的排列； 否则我们输出-1。 

约束条件允许$N$最多$10^5$，因此任何解决方案都必须在线性或近线性时间内运行。 任何涉及对排列进行回溯的事情都是立即不可能的，因为即使$O(N!)$或者$O(2^N)$接近爆炸。 甚至$O(N^2)$施工速度会太慢，因为$10^5$平方已经远远超出了极限。 

当贪婪构造选择局部最小值或最大值而不考虑未来约束时，就会出现微妙的失败情况。 例如，如果我们在看到“<”时总是尝试放置尽可能小的数字，则可能会阻塞后面需要中间较大值的“>”链。 

另一个边缘情况是长交替链，如“< > < > < ...”。 许多天真的贪婪策略在这里失败了，因为它们没有正确地将值分布在峰值和谷值上，即使有效的解决方案始终存在。 

## 方法

 暴力解释是尝试数字 1 到$N+1$并检查每一项是否满足不等式。 这是正确的，因为它直接测试有效性的定义，但它需要生成$(N+1)!$排列，甚至检查一种排列成本$O(N)$，使得总复杂度达到天文数字。 

问题的结构实际上是由相对顺序而不是绝对值决定的。 每个不平等链都会强制形成一种增加和减少部分的模式。 如果我们查看一段连续的“<”符号，则数字必须沿着该段严格增加。 类似地，一段连续的“>”符号强制采用严格递减的结构。 关键的观察是，可以通过确定哪些位置表现得像“谷”、哪些位置表现得像“峰”来逐步构建排列。 

我们不直接分配数字，而是反转角度：考虑插入从 1 到$N+1$按升序排列并决定每个数字应该放在哪里，以便所有约束保持有效。 满足此类不等式链的经典方法是通过在该块上分配递减的值来处理连续“>”符号的块，这自然需要类似堆栈的顺序反转。 

我们扫描序列并将其分成最大的段，其中不等式为“>”。 每当我们遇到这样的段时，我们就知道排列中相应的块必须以相反的顺序分配。 这导致我们通常附加索引，但在需要时反转段的结构。 

蛮力之所以有效，是因为它明确地测试了正确性，但由于阶乘增长而失败。 结构分解为单调运行的观察使我们能够在线性时间内构造有效的排列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O((N+1)! \cdot N)$|$O(N)$| 太慢了|
 | 最佳|$O(N)$|$O(N)$| 已接受 |

 ## 算法演练

 我们通过对不等式字符串进行贪婪扫描来构建答案，将位置分组为必须反转的块。 

1.初始化一个空列表`res`这将保留最终的排列。 
2. 迭代从 0 到$N$，将每个位置视为数字之间的边界。 
3. 每当我们遇到当前不等式段仅包含“>”的位置时，我们就会将索引累积到临时缓冲区中。 
4. 一旦我们按下“<”或到达末尾，我们就刷新缓冲区。 刷新意味着将收集到的索引以相反的顺序附加到`res`。 
5. 继续此过程，直到处理完所有位置，确保每个最大“>”链恰好反​​转一次。 

我们只在“>”段上反转的原因是“>”链迫使值从左到右递减。 如果我们自然地分配递增的索引，就会违反约束，因此我们在本地翻转顺序。 

### 为什么它有效

 连续“>”约束的每个最大段对放置在该段中的值强制执行严格降序。 通过按正向顺序收集索引，然后在输出时反转它们，我们确保较大的数字出现在该段的前面，较小的数字出现在后面，满足所有不等式。 在段之间，过渡点完全对应于“<”，这保留了跨块边界的自然递增顺序。 这保证了每个约束都被独立满足并且全局排列保持有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().split()
    
    res = []
    i = 0
    
    while i <= n:
        j = i
        while j < n and s[j] == '>':
            j += 1
        
        # we have a segment [i, j]
        # for '>' segment, we reverse
        for k in range(j, i - 1, -1):
            res.append(k + 1)
        
        i = j + 1
    
    print(*res)

if __name__ == "__main__":
    solve()
```该代码遵循扫描连续“>”段并反转每个此类块内索引的想法。 表达式`k + 1`将从零开始的位置转换为所需的排列值。 

关键的实现细节是正确处理边界：当我们完成“>”段时，我们必须以相反的顺序包含两个端点。 这里通常会出现相差一的错误，特别是在确定段是否结束于`j`或者`j-1`。 

## 工作示例

 ### 示例 1

 输入：```
2
< >
```我们处理位置 0 到 2。 

| 我| j | 段类型| 行动| 资源 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | “<”| 追加[1] | [1] |
 | 1 | 1 | ">" 片段立即结束 | 反转[2,1]？ 本地区块 | [1,3,2]|

 该迹线显示了单个“>”如何强制对 (3,2) 以相反的顺序排列，而“<”则允许增加开头的位置。 

生成的排列满足两个约束：1 < 3 和 3 > 2。 

### 示例 2

 输入：```
3
> < <
```我们一步步处理。 

| 我| j | 段 | 行动| 资源 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | ”>”| 反转 [1,2] | [2,1]|
 | 2 | 2 | “<”| 追加[3] | [2,1,3]|
 | 3 | 3 | “<”| 追加[4] | [2,1,3,4] |

 这表明递减前缀得到了正确处理，而其余位置遵循自然递增顺序。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(N)$| 每个索引被访问一次并追加一次 |
 | 空间|$O(N)$| 输出数组存储$N+1$价值观 |

 线性扫描足以$N \le 10^5$，并且不需要输出列表之外的额外数据结构，因此可以轻松满足内存和时间约束。

 ## 边缘情况

 一种边缘情况是完全递减的前缀，如“> > > >”。 该算法将整个前缀收集为单个段并将其反转，在开始时产生严格递减的序列。 对于输入：```
4
> > > >
```扫描形成一个覆盖所有索引 0 到 4 的段，输出变为 [5, 4, 3, 2, 1]，满足所有约束。 

另一种边缘情况是根本没有“>”符号时：```
3
< < <
```这里没有发生反转，因此索引按自然顺序附加，产生 [1, 2, 3, 4]，它正确地满足所有不等式。 

像“< > > <”这样的混合边界情况表明，该算法正确地分割成独立的单调块，确保片段之间没有交互，否则会强制产生矛盾的排序。
