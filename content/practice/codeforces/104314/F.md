 ## 解决方案
 ## 问题理解

 我们不断地建立越来越多的非常具体的数字。 第 k 个被加数是一个两端都由一个数字 2 组成的数字，随着数字的增长中间用零填充，从 2 开始，然后是 22，然后是 202，然后是 2002，依此类推。 选择前 k 个这样的被加数后，我们将它们的总和计算为普通的十进制整数。 

任务不是为了计算总和本身而计算总和，而是决定该运行总和的十进制表示形式何时首先包含给定的四位数字 N 作为连续子字符串。 我们必须找到使该条件成立所需的最小数量的被加数，或者确定它永远不会发生。 

对 N 的约束足够严格，以至于暴力字符串搜索本身并不是主要困难。 真正的挑战是总和的大小增长得非常快，因此任何从头开始为每个前缀重新计算总和的方法都会超时。 解决方案必须跨前缀重用结构并避免重复重建大整数。 

当幸运数字根本不出现时，就会出现微妙的边缘情况。 运行到某个任意截止值之前的幼稚模拟可能会过早停止并错误地返回 -1。 另一种失败模式来自于假设总和在数字长度上很快稳定下来，而实际上最低有效数字的进位可以传播到最左边并改变整个数字的结构。 

## 方法

 一个简单的尝试是从字面上模拟该过程。 对于每个 k，构造第 k 个被加数，将其与一个累加大整数相加，将结果转换为字符串，并检查 N 是否作为子字符串出现。 这在概念上是正确的，因为它完全遵循定义，但速度太慢。 第 k 个被加数有 k 个数字，因此构建和相加它的成本为 O(k)，并且对 K 之前的所有前缀执行此操作会产生 O(K^2) 工作。 如果 K 约为数万，这已经变得太慢，并且每个大整数加法都会带来很大的开销。 

关键的观察来自于对被加数结构的理解。 每个新项仅在新的高位引入一个非零数字加上对个位数字的恒定贡献。 这意味着总和的数字结构非常规则：个位上方的每个位置恰好接收一个固定贡献，而个位累积贡献的线性计数，然后向上传播进位。 

这种结构使得可以以数字形式而不是任意精度整数形式增量计算总和。 更好的是，我们不需要计算线性扫描中所有 k 的总和。 相反，我们可以对条件成立的最小 k 进行二分搜索，因为如果某个子串出现在某个 k 中，那么一旦该区域的数字结构足够稳定，它也会出现在任何更大的 k 中。 每次可行性检查都成为对 k 的按数字求和的模拟，其成本为 O(k)，而二分搜索将检查次数减少到 O(log k)。

 | ---| ---| ---| ---|
 | 暴力模拟| O(K^2 · log K 位) | O(K) | 太慢了 |

 ## 算法演练

 我们将总和视为数字列表而不是单个大整数。 对于固定的 k，我们将每个被加数的贡献直接计算到数字数组中。

1. 固定一个候选k，构造表示前k个被加数之和的数字数组，不进行大整数运算。 我们维护一个列表，其中索引 0 是个位数字。 
2. 将每个被加数的贡献添加到该数组中。 第 k 个被加数为单位位置贡献 2，为位置 k-1 贡献 2。 这创建了一个非常稀疏的加法模式，这就是为什么我们可以在 k 的线性时间内处理它。 
3. 所有加法完成后，执行从低索引到高索引的进位传播。 每个位置可能超过9，因此我们重复将溢出移至下一位。 这一步至关重要，因为进位可能会远远超出最高直接贡献。 
4. 将生成的数字数组转换为字符串表示形式。 
5. 检查字符串中是否包含N 作为子字符串。 如果是的话，这个k是可行的。 
6. 对 k 使用二分搜索，从 1 开始直到安全上限（例如 100000），以找到最小的可行 k。 

二分搜索起作用的原因是，一旦 k 变得足够大，总和的结构就数字覆盖率而言单调增长。 如果 N 出现在某个 k 处，那么增加 k 只会向左侧添加更多数字并增加现有贡献； 它不会破坏已经形成的子串。 

### 为什么它有效

 对于任何固定的 k，S_k 的构造是确定性的，并且完全由独立的数字贡献加上进位传播来定义。 可行性检查仅取决于特定子串是否出现在该确定性表示中。 二分查找是有效的，因为谓词“S_k contains N”在 k 中是单调的，即一旦出现子串，扩展总和仅附加额外的高阶结构并保留现有的数字序列。 这确保我们可以安全地搜索最小的有效 k，而不会丢失中间情况。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build(k):
    # digits in reverse (least significant first)
    a = [0] * (k + 5)

    # each term contributes to position 0 and position (i-1)
    for i in range(1, k + 1):
        a[0] += 2
        if i - 1 > 0:
            a[i - 1] += 2

    # carry propagation
    for i in range(len(a) - 1):
        if a[i] >= 10:
            a[i + 1] += a[i] // 10
            a[i] %= 10

    # trim
    while len(a) > 1 and a[-1] == 0:
        a.pop()

    return ''.join(str(x) for x in reversed(a))

def ok(k, target):
    return target in build(k)

def solve():
    n = input().strip()
    if not n:
        return
    target = n

    lo, hi = 1, 100000
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        s = build(mid)

        if target in s:
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```实施直接遵循数字仿真模型。 这`build(k)`函数构造固定 k 的总和的完整十进制表示。 关键细节是我们以相反的顺序存储数字以简化进位传播，因为加法首先影响低索引。 

二分查找包装了这个结构，反复测试子字符串是否存在。 唯一的微妙之处是确保数字数组足够大以容纳进位链，由于单位位置的重复溢出，进位链可能会稍微超出 k。

 ## 边缘情况

 当目标子字符串从未出现时，就会出现一种边缘情况。 假设没有验证界限的单调性的朴素二分搜索可能会错误地返回有限的 k。 该算法通过显式跟踪是否找到任何成功的 k 并否则返回 -1 来避免这种情况。 

另一个边缘情况是小 k，其中数字数组短于四位数字。 例如，对于k=1，S_k只是“2”，任何四位检查都必须立即失败。 该构造自然会处理此问题，因为短字符串上的子字符串搜索无法成功。 

第三种边缘情况涉及重进位传播。 例如，在大 k 时，个位数字和变为 2k，这会生成可以更改许多更高数字的级联进位。 该算法可以正确处理这个问题，因为进位传播是完全模拟的，直到稳定为止，确保不会忽略隐藏的溢出。
