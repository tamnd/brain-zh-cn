 ## 解决方案
 ## 问题理解

 我们正在维护一个动态的正整数集合，其中每个整数代表咖啡馆中新到达的成分的数量。 该集合会随着时间的推移而变化：添加新值，有时会删除最新的值块。 在这些更新之间，我们会被询问以检查是否可以同时使用所有当前可用的原料生产一定数量的相同饮料。 

该声明的一个关键观察结果是，每种饮料都必须使用所有成分，并且每种成分必须均匀分布在所有饮料中。 如果我们目前有原料数量$a_1, a_2, \dots, a_k$，然后产生$x$只有当每个$a_i$可以整除$x$。 这将整个可行性检查减少到所有活动数的整除条件。 

约束条件意味着最多$10^5$值高达的操作$10^9$。 每个查询从头开始重新计算属性的任何解决方案都会导致$O(nq)$，这太慢了。 我们需要一种方法，其中每个操作都以摊销方式处理$O(1)$或者$O(\log n)$，这意味着我们必须维护当前多重集的紧凑摘要。 

当删除删除最新元素时，会出现微妙的边缘情况。 例如，考虑从成分开始$[6, 10, 15]$，然后添加$4$，然后删除最后两个元素。 未正确维护历史记录的幼稚实现可能会意外删除较旧的元素或无法恢复正确的状态。 另一个问题是重复查询：通过扫描每个查询的所有元素来重新计算整除性的解决方案将通过小案例，但由于时间限制而在最大约束下失败。 

## 方法

 蛮力的想法很简单：维护活性成分的完整列表。 对于类型 3 的每个查询，迭代所有当前值并检查每个值是否可以被$x$。 这是正确的，因为它直接编码了问题中的条件。 但是，每个查询可能需要扫描最多$10^5$元素，并与$10^5$查询，这会导致$10^{10}$在最坏的情况下进行操作，这远远超出了可行的限度。 

关键的见解是，我们实际上并不关心个人价值观，只关心它们的共同可分结构。 一个数字$x$当且仅当它整除多重集合中的每个元素的最大公约数时。 这将问题从维护一组数字转变为维护单个聚合值：所有活动元素的 gcd。 

一旦看到这种减少，该结构就变成了堆栈问题。 由于元素仅在末尾添加并批量从末尾删除，因此我们可以维护一个堆栈，其中每个条目存储到该位置的所有元素的 gcd。 这允许有效地处理更新和回滚。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力扫描 |$O(NQ)$|$O(N)$| 太慢了 |
 | 带有前缀 gcd | 的堆栈$O(N + Q)$|$O(N)$| 已接受 |

 ## 算法演练

 我们维护一个堆栈，其中每个位置存储当前活动序列中截至该点的所有值的 gcd。 

1. 从包含初始成分前缀 gcd 的初始堆栈开始。 每个新值都会更新之前所有内容的 gcd，因此堆栈顶部始终代表迄今为止所有活性成分的 gcd。 
2. 对于类型 1 查询，附加新成分。 我们用当前栈顶计算这个值的 gcd 并压入它。 这是有效的，因为 gcd 是关联的，因此前缀结构在扩展后仍然有效。 
3. 对于类型 2 查询，我们删除最后一个$K$从堆栈中弹出成分$K$次。 每次弹出都会消除最新成分的贡献，同时保留较早前缀 gcd 值的正确性。 
4. 对于类型 3 的查询，我们检查请求的号码是否$X$除以堆栈顶部存储的当前 gcd。 如果是，则所有元素都可以被整除$X$，否则至少有一个元素不兼容，订单无法履行。 

### 为什么它有效

 在任何时刻，栈顶都代表$\gcd(a_1, a_2, \dots, a_k)$超过所有活性成分。 由于一个数字当且仅当它整除它们的 gcd 时才能整除集合中的所有元素，因此根据该单个值检查整除性相当于单独检查所有元素。 堆栈不变式被保留，因为 gcd 更新是关联的，并且删除准确地恢复了先前的前缀状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from math import gcd

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    # stack stores prefix gcds
    st = [0]
    for x in a:
        st.append(gcd(st[-1], x))

    for _ in range(q):
        tmp = input().split()
        t = int(tmp[0])

        if t == 1:
            g = int(tmp[1])
            st.append(gcd(st[-1], g))

        elif t == 2:
            k = int(tmp[1])
            # pop k elements
            for _ in range(k):
                st.pop()

        else:
            x = int(tmp[1])
            if st[-1] % x == 0:
                print("SIM")
            else:
                print("NAO")

if __name__ == "__main__":
    solve()
```该实现依赖于堆栈存储前缀 gcd 而不是原始值。 这可以避免在查询期间重新计算整个数组的 gcd。 唯一微妙的部分是确保删除正确删除最新的前缀状态； 由于每个堆栈条目仅依赖于前一个条目，因此弹出会自动恢复前一个有效的 gcd。 

一个值得注意的细节是初始堆栈从零开始，它充当 gcd 的中性元素。 这确保了第一个真实成分正确地初始化了结构。

 ## 边缘情况

 单一成分输入测试 gcd 初始化是否正确处理具有一个有意义元素的堆栈。 该算法仍然有效，因为单个数字的最大公约数是其本身，并且整除性检查可以正确减少。 

恢复早期状态的大量删除测试堆栈是否正确恢复到以前的前缀 gcd 值。 由于每个堆栈条目都编码一个完整的前缀，因此多次弹出总是会恢复有效的历史 gcd，而无需重新计算。 

统一数组（例如所有相等的数字）可确保 gcd 在更新过程中保持稳定，从而确认在重复的 gcd 计算中不会出现意外的副作用。 

使堆栈保持初始状态的边界移除确认哨兵零值行为正确并且不会干扰整除性检查。
