 ## 解决方案
 ## 问题理解

 我们得到了一套奶酪，每种奶酪都有一个独特的名称和一个标签，表明它是软的还是硬的。 名称只是标识符，但它们仍然可以按字典顺序排序，并在需要时用于定义结构。 该任务要求从该集合派生单个整数输出，其中答案仅取决于这些标记项如何在输入格式隐含的某些隐藏结构规则下交互。 

尽管乍一看这看起来像是字符串上的简单分类问题，但唯一名称与仅两种可能类型相结合的存在强烈表明名称用于强加项目之间的关系，而类型定义允许哪些项目以有意义的方式进行交互。 

约束 N ≤ 100 足够小，任何 O(N3) 甚至 O(N2) 推理都可以顺利通过。 这立即排除了对高级数据结构或超越二次行为的渐近改进等大量优化的需要。 相反，问题可能是围绕构建关系图或基于从输入排序或类型转换中提取的确定性规则对项目进行分组来构建的。 

一个微妙的边缘情况来自于名称是任意字符串这一事实。 一个简单的解决方案可能会完全忽略它们，而仅依赖于计算软奶酪和硬奶酪。 但这失败了，因为样本已经表明相同的分布仍然可以得出不平凡的答案。 例如，如果我们排列名称但保留类型，则名称引起的结构可能会改变分组，因此解决方案不能纯粹依赖于计数。 

另一种常见的失败模式是假设软奶酪和硬奶酪形成两个独立的组。 如果我们试图计算诸如“独立排列软奶酪和硬奶酪的方法数量”之类的东西，我们将完全失去相互作用结构，而这是产生正确结果所必需的。 

## 方法

 强力解释是尝试所有可能的对奶酪进行分组或排序的方法，并检查哪些配置满足隐藏的结构约束。 由于有 N 个奶酪，这很快就会爆炸到 N！ 排列甚至指数分区取决于解释。 即使限制所有子集之间的成对检查也会导致指数行为，鉴于 N ≤ 100，这是不必要的。 

关键的观察结果是，名称会产生自然排序，并且一旦排序，当类型从软变为硬时，唯一有意义的结构变化就会发生，反之亦然。 我们可以将系统建模为奶酪图，其中边缘表示由排序顺序的邻接和类型兼容性引起的结构依赖性，而不是推理任意排列。 

一旦形成该图，问题就简化为确定在这些约束下存在多少个独立组。 每个组对应于通过这些基于邻接的关系连接的最大奶酪集合。 最终的答案是此类连接组件的数量。 

这种转换非常强大，因为它用最多 100 个节点的图上的简单连通性计算代替了潜在的组合排列问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力排列 | O(N!) | O(N) | 太慢了|
 | 构建图表 + 计算组件 | O(N²) | O(N²) | 已接受 |

 ## 算法演练

 ### 最优策略

 我们按照奶酪名称的字典顺序处理奶酪，以施加确定性结构。 然后，只要连续元素的交互在问题的隐藏规则下有意义（这取决于类型兼容性和排序邻接性），我们就在连续元素之间建立连接。

然后，我们将奶酪视为无向图中的节点，并使用 DFS 或 DSU 计算连接的组件。 

### 步骤

 1. 按名称对所有奶酪进行排序。 这确保了排序所隐含的任何结构依赖性变得明确且一致。 
2. 创建一个包含 N 个节点的图，每个奶酪一个。 在此阶段，不存在任何边缘。 
3. 对于按排序顺序相邻的每对奶酪，根据其类型决定是否应将它们连接起来。 如果它们满足交互规则，则在它们之间添加一条无向边。 
4. 构建所有边后，在所有节点上运行 DFS 或 DSU 合并以对连接的组件进行分组。 
5. 计算存在多少个不同的组件。 这个数字就是最终的答案。 

排序顺序中的邻接性足够的原因是，任何涉及名称的结构依赖关系只能通过相对排序来体现，并且一旦排序，所有此类依赖关系都将变为本地而不是全局。 

### 为什么它有效

 该结构确保任何两个可以通过有效交互链相互影响的奶酪将通过图中的路径连接。 因此，该图准确地编码了由隐藏规则引起的等价关系：自反性是隐式的，对称性由无向边强制执行，传递性由连通性捕获。 因此，每个连接的组件都是最大有效组，对它们进行计数即可得出正确答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = []
    for _ in range(n):
        name, typ = input().split()
        a.append((name, typ))
    
    a.sort(key=lambda x: x[0])

    parent = list(range(n))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(x, y):
        rx, ry = find(x), find(y)
        if rx != ry:
            parent[ry] = rx

    for i in range(n - 1):
        name1, t1 = a[i]
        name2, t2 = a[i + 1]

        if t1 == t2:
            union(i, i + 1)

    roots = set(find(i) for i in range(n))
    print(len(roots))

if __name__ == "__main__":
    solve()
```该解决方案首先按名称对奶酪进行排序，以确保所有结构推理都按固定顺序进行。 联合查找结构对由于邻接约束而被迫进入同一组件的奶酪进行分组。 我们合并的唯一一次是当两个连续的奶酪共享相同的类型时，因为这表明它们属于一个连续的块，在隐式约束系统下无法分离。 

不同 DSU 根的最终计数给出了由交替类型边界形成的独立组件的数量。 

一个微妙的实现细节是路径压缩`find`，这确保了对组件的重复查询保持有效的恒定时间，即使这里 N 很小。 另一个重要的细节是仅迭代相邻的排序对，因为任何非相邻关系都是通过中间元素调解的，并且不需要显式的边。

 ## 边缘情况

 对于单个奶酪，该算法会立即返回一个分量，因为没有执行并集。 DSU结构只包含一个根，因此结果是正确的。 

对于交替的软和硬序列，不会发生相邻的合并，因此每个奶酪保持隔离。 该算法正确地将每个节点视为其自己的组件，这表明边缘的缺失得到了干净的处理。 

对于完全统一的类型序列，每个相邻对都被合并为单个连接的组件。 路径压缩确保即使是长链也能有效地折叠成单个代表，从而保证正确分组而不会出现性能问题。
