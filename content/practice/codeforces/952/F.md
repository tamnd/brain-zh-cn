 ## 问题理解

 输入是一个简短的算术表达式，包含小的非负整数和只有两个运算：加法和减法。 除了通常的中缀表示法之外，没有括号，没有乘法，也没有隐藏的格式规则。 

任务不是计算抽象意义上的数学上正确的值，而是准确地再现已知有缺陷的参考实现对于相同表达式的输出。 这意味着我们正在有效地对原始评估器处理表达式的方式进行逆向工程。 

由于操作数最多为 10 个，每个操作数最多为 255 个，因此表达式长度很小。 任何扫描字符串一次或几次的解决方案就已经足够了。 即使二次行为也无关紧要，但该结构表明单个线性通道是预期的方向。 

这里的一个天真的错误是假设标准运算符优先级规则或尝试实现完整的表达式解析器。 这仍然会给出正确的数学结果，但如果它忽略优先级或以不同的方式处理令牌，它可能与有缺陷的评估器不匹配。 

一个微妙的失败案例来自于将表达式解释为一般算术语法。 例如，将其视为需要调车场或堆栈评估是不必要的复杂性，并且如果实施不正确，很容易引入预期模型中不存在的优先错误。 

另一个边缘情况是过度思考负值。 由于操作数保证在 0 到 255 之间，并且没有一元减号，因此每个数字始终是一个独立的标记，因此解析可以安全地假设数字、运算符、数字等的严格交替模式。 

## 方法

 暴力解释是将表达式完全解析为标记并使用标准表达式求值器对其求值。 这通常涉及转换为后缀表示法或使用两个堆栈来存储值和运算符。 这对于一般算术表达式来说是正确的，但这里引入了不必要的机制。 从概念上讲，开销是 O(n)，但具有很大的常数因子，更重要的是，如果优先级规则处理不当，它可能会偏离实际的评估顺序。 

关键的观察结果是表达式仅包含两个在预期评估模型中具有相同优先级的运算符。 该表达式很短，并且每个操作数都由运算符显式分隔，这强烈建议对标记进行一次从左到右的折叠。 这减少了维护累加器并应用每个操作的问题。 

参考解决方案中的“bug”与严格从左到右处理表达式而没有任何优先级问题一致，这也是该语法的最简单的可能解释器。

 ## 算法演练

 我们将表达式作为数字和运算符的序列进行处理，始终将下一个运算立即应用于运行总计。

1. 从字符串中读取第一个数字并将其设置为结果的初始值。 这确定了折叠的起点。 
2. 从左到右扫描字符串。 每次遇到运算符时，我们都知道下一个标记是数字。 
3. 完全解析下一个整数（它可能有多个数字）。 这确保我们正确使用整个操作数，而不是单独处理数字。 
4. 立即将算子应用到运行结果上。 如果运算符是“+”，我们将数字相加。 如果是“-”，我们就减去它。 
5. 继续，直到到达字符串末尾。 此时，累加器保存参考评估器产生的最终值。 

### 为什么它有效

 正确性来自于输入的结构：每个运算符直接连接两个完整的操作数，并且在预期的评估模型中没有一个运算符比另一个运算符具有更高的优先级。 由于在有缺陷的实现中评估是严格顺序的，因此维护单个运行的累加器可以保留完全相同的中间状态。 在每一步中，累加器都等于参考解在处理表达式的前缀后将具有的值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    
    i = 0
    
    # read first number
    cur = 0
    while i < n and s[i].isdigit():
        cur = cur * 10 + (ord(s[i]) - 48)
        i += 1
    
    # process remaining operators and numbers
    while i < n:
        op = s[i]
        i += 1
        
        num = 0
        while i < n and s[i].isdigit():
            num = num * 10 + (ord(s[i]) - 48)
            i += 1
        
        if op == '+':
            cur += num
        else:
            cur -= num
    
    print(cur)

if __name__ == "__main__":
    solve()
```解决方案是单次线性扫描。 第一个循环隔离初始操作数，以便在应用任何操作之前正确初始化累加器。 第二个循环在读取运算符和解析下一个数字之间交替，确保严格遵守表达式结构。 

解析采用手动数字累加代替`split`，这避免了格式化周围的边缘情况，并保持对令牌边界的完全控制。

## 边缘情况

 第一个边缘情况是一个以零开头的单位数表达式。 例如，`0+0`。 该算法直接从第一个数字初始化累加器，因此它可以正确处理零，而不需要特殊的大小写。 

第二种边缘情况涉及最大值操作数，例如`255-255+255`。 解析循环将数字安全地累积为整数，而无需担心 Python 中的溢出问题，并且每个操作都会立即应用，因此中间值保持正确。 

第三种边缘情况是一个长的交替减法链，例如`1-2-3-4-5`。 该算法按顺序重复应用减法，与参考评估器从左到右的行为完全匹配。 每个中间结果都保存在累加器中，因此不会出现优先级歧义。
