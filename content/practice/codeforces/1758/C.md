 ## 解决方案
 ## 问题理解

 我们需要构造一个整数的排列`1`到`n`具有三个特殊要求。 

第一个位置必须包含`x`。 最后一个位置必须包含`1`。 对于每个职位`i`从`1`到`n-1`，放置在那里的值必须是`i`。 

在所有有效的排列中，我们需要字典顺序最小的排列。 如果不存在有效排列，我们输出`-1`。 

约束足够大，我们必须直接构建答案。 全部的总和`n`值最多是`2·10^5`，这意味着`O(n log n)`甚至`O(n√n)`只要所有测试用例的总工作量保持接近线性，每个测试用例的解决方案就可以。 对排列进行强力搜索是不可能的。 即使是为了`n = 15`，已经有超过一万亿种排列。 

出现微妙的边缘情况时`x`不分开`n`。 

例如：```
n = 5, x = 4
```第一个位置包含`4`。 最终的价值`5`一定会出现在某个地方。 由于除最后一个位置之外的每个位置都必须包含其索引的倍数，因此无法路由所需的值以使所有约束都成立。 正确答案是：```
-1
```另一个容易犯的错误是假设放置`x`在位置`1`和`1`在位置`n`自动确定其余部分。 

考虑：```
n = 12, x = 3
```这两个修改的恒等排列无效，因为从位置中删除了值`1`必须在保留所有可分性限制的同时重新定位。 

第三个微妙点是词典编纂的极简性。 我们不仅仅是在寻找任何有效的排列。 如果存在多个有效排列，我们必须使从左到右的每个位置尽可能小。 

## 方法

 蛮力方法将生成排列并测试每个位置是否满足整除条件。 即使检查大小为 15 的所有排列也已经无望，因此我们需要利用约束的结构。 

关键的观察结果是恒等排列已经满足整除性要求，因为每个数字都是其自身的倍数。 

如果没有职位限制的话`1`和`n`，排列```
1 2 3 ... n
```将是有效的。 

唯一的问题是这个位置`1`必须包含`x`和位置`n`必须包含`1`。 

这表明从身份排列开始并仅修改一小部分位置链。 可分性条件极其严格。 如果位置`i`不包含`i`，那么它必须包含一些更大的倍数`i`。 

假设我们放置`x`在位置`1`。 那么原来属于position的值`x`必须搬到其他地方。 重复这个参数会创建一个位置链，其中每个下一个位置都是前一个位置的倍数。 

为了存在解决方案，我们最终需要达到以下目标`n`。 这立即意味着`x`必须划分`n`。 如果`x`不分开`n`，不存在有效链。 

为了获得字典序上最小的答案，我们总是希望最早改变的位置接收尽可能小的有效值。 这导致从当前位置贪婪地过渡到仍然允许达到的最小除数倍数`n`。 

由此产生的构造遵循除数链`x`到`n`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了|
 | 贪心除数链 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.如果`n`不能被整除`x`， 输出`-1`。 
2. 将排列初始化为恒等排列：```
p[i] = i
```3. 设置：```
p[1] = x
p[n] = 1
```4.让`cur = x`。 
5. 虽然`cur != n`，找到最小的倍数`next`的`cur`这样：

 -`next`划分`n`-`next > cur`在所有这些候选者中，选择最小的一个。 
6. 设置：```
p[cur] = next
```并移动：```
cur = next
```7.到达后`n`， 放：```
p[n] = 1
```8. 输出排列。 

贪心选择是解决方案的核心。 在每一步中，我们选择最小的有效下一个除数`n`这也是当前位置的倍数。 任何更大的选择都会增加排列的较早位置，从而产生字典序上更大的答案。 

### 为什么它有效

 每个修改的位置都属于一条链```
1 -> x -> ... -> n -> 1
```每次转换都会从一个数字到其倍数之一，因此仍然满足整除性要求。 

链外的所有位置都保持原来的值，也满足可分性要求。 

该链仅使用除数`n`，所以每一步最终都可以达到`n`。 如果`x`不分开`n`，这样的链不可能存在，因为每一步都保留了与`n`。 

贪心规则在存在选择的最早位置选择可能的最小下一个值。 字典顺序由第一个不同的位置决定，因此这保证了最小的有效排列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, x = map(int, input().split())

        if n % x != 0:
            print(-1)
            continue

        p = list(range(n + 1))

        p[1] = x
        p[n] = 1

        cur = x

        while cur != n:
            nxt = n

            d = cur * 2
            while d <= n:
                if n % d == 0 and d % cur == 0:
                    nxt = d
                    break
                d += cur

            p[cur] = nxt
            cur = nxt

        print(*p[1:])

solve()
```排列从恒等排列开始，因为它已经满足所有可分性约束。 

唯一改变的位置是除数链上的位置。 对于当前职位`cur`，我们搜索多个`cur`并选择仍然可以划分的最小的一个`n`。 这一选择保留了最终达到目标的可能性`n`同时使排列按字典顺序最小化。 

一个常见的实施错误是忘记了`p[n]`最终必须是`1`。 另一个是替换链外的位置。 每个未触及的位置应保持等于其索引。

## 测试用例```python
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    out = []

    t = int(input())

    for _ in range(t):
        n, x = map(int, input().split())

        if n % x:
            out.append("-1")
            continue

        p = list(range(n + 1))
        p[1] = x
        p[n] = 1

        cur = x

        while cur != n:
            nxt = n

            d = cur * 2
            while d <= n:
                if n % d == 0 and d % cur == 0:
                    nxt = d
                    break
                d += cur

            p[cur] = nxt
            cur = nxt

        out.append(" ".join(map(str, p[1:])))

    return "\n".join(out)

# provided samples
assert run("3\n3 3\n4 2\n5 4\n") == (
    "3 2 1\n"
    "2 4 3 1\n"
    "-1"
)

# minimum valid case
assert run("1\n2 2\n") == "2 1"

# impossible because x does not divide n
assert run("1\n10 6\n") == "-1"

# direct chain
assert run("1\n6 3\n") == "3 2 6 4 5 1"

# larger divisor chain
assert run("1\n12 3\n") == "3 2 6 4 5 12 7 8 9 10 11 1"

 ## 边缘情况

 考虑：```
n = 5
x = 4
```自从`5 % 4 != 0`，算法立即返回：```
-1
```没有除数链`4`可以达到`5`，因此不存在有效的排列。 

考虑：```
n = 2
x = 2
```恒等排列变为：```
2 1
```链条开始于`2`，这已经是`n`，因此不需要进一步的工作。 

考虑：```
n = 16
x = 2
```链条变成：```
2 -> 4 -> 8 -> 16
```该算法精确更新这些位置，并保持所有其他位置不变。 每个分配的值都是其位置的倍数，并且每一步的贪婪选择都会产生字典顺序上最小的有效排列。
