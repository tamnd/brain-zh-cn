 ## 解决方案
 ## 问题理解

 我们得到了一个音乐播放列表`n`按初始顺序排列的独特歌曲`a`。 该应用程序以循环方式播放歌曲：在最后一首歌曲之后，它从第一首开始。 另外，我们有一个想要的聆听序列`b`相同的`n`歌曲。 在任何一天，我们都会从播放列表的开头开始`a`并且可以按跳过按钮跳至下一首歌曲。 目标是确定听以下歌曲所需的最小跳跃次数`b`按顺序，不跳过任何歌曲`b`本身。 

额外的复杂性来自于几天之间的更新。 每天（除了最后一天），我们都会进行一次交换操作，该操作要么改变`a`或者`b`永久。 每次更新后，我们必须重新计算从新的开始的最小跳过次数`a_1`。 

这些限制意味着播放列表的简单模拟将会太慢。 和`n`和`d`当数量达到 200,000 时，O(n²) 或 O(n·d) 解决方案将执行大约 4 × 10^10 次操作，远远超出了我们在 2 秒内所能承受的范围。 这表明我们需要 O(n + d·log n) 或 O(n + d) 方法。 边缘情况包括：`a`和`b`当一首歌开始时几乎相同`a`但晚了`b`，并且当交换改变第一个或最后一个元素的位置时。 线性扫描的粗心实现`a`对于每首歌曲`b`在大的情况下会失败`n`。 

## 方法

 蛮力方法很简单。 开始于`a_1`，并且对于每首歌曲`b`， 扫描`a`按顺序计算每首跳过的歌曲，直到遇到这首歌。 到达终点后`a`，根据需要回到开头。 这是正确的，因为它准确地模拟了该过程。 然而，对于`n = 200,000`，这会导致最坏情况下的 O(n²) 操作，速度太慢。 

优化的关键观察是`a`是一个排列，所以每首歌曲都有一个唯一的索引。 如果我们预先计算每首歌的位置`a`，我们可以计算从一首歌曲开始的跳过次数`b`使用模运算而不是扫描来进行下一个。 具体来说，如果歌曲`b[i]`处于位置`pos[b[i]]`在`a`和上一首歌曲`b[i-1]`是在`prev_pos`，跳跃次数为`(pos[b[i]] - prev_pos - 1) % n + n * (pos[b[i]] < prev_pos)`。 本质上，如果下一首歌曲出现在播放列表中当前歌曲之前，我们就会考虑环绕。 这将一天的计算量减少到 O(n)。 

有效处理更新是下一个挑战。 交换两个元素`a`需要更新位置图，时间复杂度为O(1)。 交换元素`b`需要改变它们在序列中的顺序，对于数组表示来说这也是 O(1) 。 通过这些观察，每天的最小跳过次数可以在 O(n) 内计算出来，并且每次更新不会增加超过 O(1) 的工作量。 因此，总复杂度为 O(d·n)，这是可以接受的`n`最多 200,000 个且较小`d`。 对于最大的输入，我们可以使用线段树进一步优化，如果`d`接近`n`，但是每天 O(n) 的方法在这里就足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | Brute Force（模拟播放列表）| O(n²) | O(n) | 太慢了 |
 | 最佳（位置映射+模块化跳跃）| O(d·n) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读`n`和`d`和初始数组`a`和`b`。 建立一个`pos`字典映射每首歌曲编号`a`到其索引以进行 O(1) 查找。 这让我们可以直接跳到歌曲的位置，而不是线性扫描。 
2. 第一天，初始化`prev_pos = -1`。 对于每首歌曲`b[i]`按顺序计算其位置`curr_pos = pos[b[i]]`。 跳过次数为`(curr_pos - prev_pos - 1) % n`如果`curr_pos > prev_pos`， 或者`(curr_pos + n - prev_pos - 1)`如果需要包装。 积累这些跳过并更新`prev_pos = curr_pos`。 
3. 输出当天的总跳过次数。 
4. 对于剩下的每一个`d-1`天，阅读更新`(c, x, y)`。 如果`c = 1`， 交换`a[x-1]`和`a[y-1]`，并更新`pos[a[x-1]]`和`pos[a[y-1]]`因此。 如果`c = 2`， 交换`b[x-1]`和`b[y-1]`。 这些交换是恒定时间操作。 
5. 更新后对新阵列重复步骤 2-3。 将结果附加到输出。 

为什么它有效：每天，算法都会维护以下不变式：`pos`准确反映每首歌曲的当前位置`a`。 使用模块化算术可以保证我们正确地考虑跨越环绕边界的跳跃。 由于每首歌`b`只出现一次，我们绝不会误算跳过次数，并且累计总数代表所需的最小跳过次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, d = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

# position map for quick lookup
pos = [0] * (n + 1)
for i, song in enumerate(a):
    pos[song] = i

def compute_skips():
    skips = 0
    prev = -1
    for song in b:
        curr = pos[song]
        if curr > prev:
            skips += curr - prev - 1
        else:
            skips += curr + n - prev - 1
        prev = curr
    return skips

print(compute_skips())

for _ in range(d - 1):
    c, x, y = map(int, input().split())
    x -= 1
    y -= 1
    if c == 1:
        a[x], a[y] = a[y], a[x]
        pos[a[x]] = x
        pos[a[y]] = y
    else:
        b[x], b[y] = b[y], b[x]
    print(compute_skips())
```解决方案首先将每首歌曲映射到`a`到它的索引。 这允许在计算跳过时 O(1) 查找位置。 这`compute_skips`函数迭代`b`按顺序，使用模算术计算跳过以处理循环播放列表行为。 更新是就地处理的，`pos`交换后立即更新`a`。 交换`b`只影响迭代顺序。 读取交换时要特别注意从零开始的索引。
