 ## 解决方案
 ## 问题理解

 我们得到了一个一一显示的整数序列。 每个新数字出现后，我们需要确定是否可以通过取出两个较早的数字并按顺序连接它们的十进制表示形式来“构造”它，而无需在中间插入任何内容。 

例如，如果之前我们看到 12 和 3，那么 123 被认为是可构造的，因为写“12”后跟“3”会得到“123”。 即使两个部分是相同的早期数字，只要它们都在当前位置之前看到，同样的想法也适用。 我们计算在序列中，当前数字可以通过两张先前看到的卡片以这种方式形成的次数。 

输入大小最大可达一百万个数字，每个数字最大可达$10^6 - 1$，所以每个数字最多有 6 位数字。 这立即表明任何解决方案都必须在大致恒定或对数时间内处理每个数字。 二次或偶数$O(n \sqrt{n})$方法是不可能的，因为即使$10^6$每个元素的操作已经太大了。 

关键的困难在于，我们没有被要求检查简单的隶属条件，而是检查结构化的分解：每个数字都必须针对其十进制字符串所有可能的拆分为两个非空部分进行测试，并且这两个部分都必须对应于之前看到的值。 

有一些微妙的边缘情况打破了简单的方法。 

如果数字包含零，则连接严格表现为字符串相等，而不是数字相等。 例如，如果我们看到 0 和 1，则连接为“01”，它与整数 1 不匹配。因此，将数字单独视为整数而不保留精确的字符串形式会导致不正确的匹配。 

另一个微妙的情况是重复值。 如果我们之前看到过一次 7，那么数字 77 就不能从“7 + 7”构造出来，除非 7 之前至少出现过两次。 仅跟踪集合中存在性的解决方案会错误地计算这种情况。 

最后，前导零通过字符串结构隐含地起作用。 由于输入数字没有前导零，因此产生以零开头的左侧或右侧部分的任何分割仍然对应于有效的整数表示，但它必须与现有的先前看到的数字完全匹配，而不是标准化版本。 

## 方法

 最直接的方法是保留所有以前见过的数字的记录。 对于每个传入的数字，我们将其转换为字符串并尝试每个可能的分割点。 对于一个数字$d$数字，我们尝试$d - 1$分裂。 对于每次分割，我们检查这两个部分是否存在于之前看到的数字中。 如果是，我们增加答案。 

这是可行的，因为每个有效的构造都必须恰好对应于字符串表示形式的一个分割。 然而，正确性取决于使用频率计数而不是简单的集合，因为相同的数字可能需要两次。 

对于每个数字，暴力版本将扫描所有先前的数字对并测试串联。 这就需要$O(n)$每个查询的候选者，导致$O(n^2)$总的操作，这远远超出了可行的范围$n = 10^6$。 

关键的观察是串联结构消除了全局搜索对的需要。 相反，每个数字仅与其自己的分割边界相互作用。 这将问题减少到每个数字最多检查 5 次分割（因为值最多为 6 位数字），并且每次检查都是一个$O(1)$字典查找。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解对 |$O(n^2)$|$O(n)$| 太慢了 |
 | 使用哈希映射进行拆分检查 |$O(n \cdot d)$,$d \le 6$|$O(n)$| 已接受 |

 ## 算法演练

 我们从左到右处理序列，同时维护迄今为止看到的所有数字的频率图。 

1. 将当前数字转换为其字符串表示形式。 这是必要的，因为串联取决于数字边界，而不是算术值。 
2. 对于字符串中每个可能的分割位置，将其分为左部分和右部分。 每个分割对应于一对潜在的较早的卡片，它们的串联可能形成当前的数字。 这是唯一可以产生有效构造的结构。 
3. 将这两个部分转换回整数，并检查它们是否存在于先前看到的数字的频率图中。 
4. 如果两个部分相等，请确保该数字在前面的元素中出现的频率至少为 2，因为我们需要两次不同的出现才能形成该对。 
5. 如果任何分割满足条件，则将此位置视为有效的“声音事件”。 
6. 处理当前数字后，增加其在地图中的频率，以便可用于将来的构造。 

### 为什么它有效

 在每一步中，频率图准确地表示当前索引之前的所有可用卡。 当前数字的任何有效构造都必须对应于将其十进制表示形式拆分为两个连续的子字符串。 没有其他方法可以形成数字，因为串联可以毫无间隙地保留数字顺序。 由于检查了每个可能的分解，并使用精确计数验证了存在性，因此不会遗漏任何有效对，也不接受无效对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    a = list(map(int, input().split()))
    
    freq = {}
    ans = 0

    for x in a:
        s = str(x)
        ok = False

        for i in range(1, len(s)):
            left = int(s[:i])
            right = int(s[i:])

            if freq.get(left, 0) > 0 and freq.get(right, 0) > 0:
                if left != right:
                    ok = True
                    break
                else:
                    if freq.get(left, 0) > 1:
                        ok = True
                        break

        if ok:
            ans += 1

        freq[x] = freq.get(x, 0) + 1

    print(ans)

if __name__ == "__main__":
    main()
```该解决方案的核心是增量频率图。 它确保我们只考虑以前见过的牌。 split 循环受位数限制，最多为 6，因此每个元素的时间保持恒定。 

唯一微妙的实现细节是对等分割的处理。 当两半的计算结果为相同的整数时，我们必须确保至少有两次较早的出现，因为单张卡不能重复使用两次。

 ## 边缘情况

 一种边缘情况被重复分割成相同的数字。 考虑输入：```
7 7 77
```处理第二个 7 时，不存在分割。 当处理 77 时，分割是 (7,7)，但正确性取决于前面有两个 7。 由于此时只有一个存在，因此检查正确地拒绝了它。 

另一种边缘情况涉及包含零的数字：```
3 0 1 1
```当最后计算 1 时，分割“01”无效，因为它与存储的整数 1 不完全匹配。 该算法避免了这种不匹配，因为它依赖于存储值的整数相等性，而不是单独的子字符串相等性。 

最后一个边缘情况是可构造数字的长链。 即使每个数字都是有效的，每个步骤也仅依赖于恒定时间的分割检查，因此算法保持稳定并且不会随着序列的增长而退化。
