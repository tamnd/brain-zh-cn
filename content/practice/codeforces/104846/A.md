 ## 解决方案
 ## 问题理解

 我们有两种类型的书。 有A数学书和B编程书。 每本数学书都贡献 X 个新事实，每本编程书都贡献 Y 个新事实。 所有书籍中的所有事实都是不同的，因此选择的总知识只是所选书籍的线性总和。 

Ira 最多可以在书架上放置 K 本书。 任务是选择书籍的子集，遵守限制 K，以使事实总数最大化。 

所以结构很简单：我们有值 X 的 A 副本和值 Y 的 B 副本，并且我们总共最多可以选择 K 个项目。 我们想要最大可实现的金额。 

测试之间的约束很大，A 或 B 的约束大约为 10^12。这立即排除了任何每本书的模拟或子集枚举。 即使每次测试对所有书籍进行线性扫描也可以，但是如果在 K 循环内天真地完成每单位书籍选择的迭代，那么任何迭代都会太慢。 

当其中一个类别为空时，就会出现微妙的失败情况。 如果 A = 0 或 B = 0，贪婪混合策略仍然必须正确地减少到从单个池中挑选。 另一种情况是当K超过A+B时，我们不能完全填满书架，只能拿走所有的书。 

例如，如果 A = 3、B = 0、K = 5、X = 10、Y = 1，则正确答案是 30，而不是 50 或任何涉及填充不存在的书籍的内容。 

另一个极端情况是当一种类型在值上占主导地位但在数量上稀缺时，例如 A = 2、B = 100、K = 50、X = 1000、Y = 1。如果逻辑编写不正确，只采用好看类型的 min(K, B) 而不考虑可用性的幼稚策略将会失败，但正确的方法自然会处理上限。 

## 方法

 如果我们以最直接的方式思考，我们可以尝试各种方法来选择 i 部数学书和 j 部编程书，使得 i + j ≤ K、i ≤ A、j ≤ B。对于每一对，我们计算 i·X + j·Y 并取最大值。 这是正确的，但搜索空间是 O(K)，因为对于每个 i 我们确定 j，反之亦然。 当 K 很大时，这就变得不可行。 

一旦我们注意到每个项目类型只有两个值，结构就会简化。 每本数学书都是相同的，每本编程书都是相同的。 这消除了任何组合的复杂性：唯一有意义的决定是我们采取每种类型的多少本书。 

此时，问题就简化为从两个桶中选择最多 K 个项目。 如果 X 大于 Y，则在 A 和 K 的限制下，首先获取尽可能多的数学书总是最佳的，然后用编程书填充剩余容量。 如果 Y 更大，我们交换角色。 这是通过交换证明的经典贪婪选择：任何使用较低价值的书而仍然有较高价值的书的解决方案都可以通过交换来改进。 

蛮力之所以有效，是因为它显式枚举了 K 的所有分割，但当 K 很大时，它会失败，因为分割的数量随 K 线性增长。观察到每种类型中所有项目都是相同的，我们可以将决策折叠为最多两个确定性选择。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解 | O(K) | O(1) | O(1) | 太慢了 |
 | 贪心按值排序 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立对待每个测试。 

## 算法演练

1. 比较 X 和 Y 以确定哪种类型的书每单位更有价值。 这就确定了我们挑选书籍的顺序。 
2. 首先选择较高的值。 假设X≥Y，那么我们首先拿数学书。 如果 Y > X，我们对称地从编程书籍开始。 原因是任何最佳解决方案都必须尽可能优先考虑更高价值的项目。 
3. 尽可能多地从更好的类别中选择书籍：如果数学更好，则首先选择 = min(K, A)，如果编程更好，则选择 min(K, B)。 
4、减少剩余容量：K先变成K-。 
5. 从第二类中取出尽可能多的书：第二个 = min(K, B) 或 min(K, A)，具体取决于剩余的书籍。 
6. 计算总值：first_count × value_first + secondary_count × value_second。 

每一步都受到这样的约束：我们最多只能获取 K 本书，并且不能超出每个类别的可用量。 

### 为什么它有效

 任何有效选择仅由计数 (i, j) 定义，其中 i ≤ A、j ≤ B、i + j ≤ K。假设存在一个解决方案，其中选择了较低价值的书籍，而较高价值的书籍仍然可用并且容量仍然存在。 用一本较高价值的书替换一本较低价值的书会严格增加总金额并保持可行性。 重复此交换论证会将任何最佳解决方案转换为首先在约束允许的范围内耗尽较高价值类别，然后使用另一个类别的解决方案。 这保证了贪婪排序是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(A, B, K, X, Y):
    if X >= Y:
        take_x = min(A, K)
        K -= take_x
        take_y = min(B, K)
        return take_x * X + take_y * Y
    else:
        take_y = min(B, K)
        K -= take_y
        take_x = min(A, K)
        return take_x * X + take_y * Y

def main():
    data = sys.stdin.read().strip().split()
    t = 10
    idx = 0
    out = []
    for _ in range(t):
        A = int(data[idx]); B = int(data[idx+1]); K = int(data[idx+2])
        X = int(data[idx+3]); Y = int(data[idx+4])
        idx += 5
        out.append(str(solve_case(A, B, K, X, Y)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该实现直接反映了贪婪结构。 关键的决策是X和Y之间的比较，它决定了消费的顺序。 每个测试都是恒定时间，因为我们只执行一些算术运算和最小计算。 

必须注意，取完第一批后更新K； 否则第二次选择将错误地忽略容量限制。 此外，由于界限较大，所有算术都可以安全地适合 Python 整数。

 ## 边缘情况

 当 A = 0 或 B = 0 时，算法自然减少，因为其中一个 min 调用变为零。 例如，如果 A = 0 且 X ≥ Y，我们对数学书籍取 min(0, K) = 0，然后对所有可能的编程书籍取 K 为止。代码无需特殊分支即可处理此问题。 

当K≥A+B时，两个分支都会完全消耗可用的书籍。 第一个分钟根据顺序饱和到 A 或 B，然后第二个分钟将余数达到另一个完整计数，产生 A·X + B·Y。 

当 X = Y 时，顺序并不重要。 该算法仍然首先选择一个类别，但由于值相同，因此任何拆分都会产生相同的总和。
