 ## 解决方案
 ## 问题理解

 一位商人沿着河道旅行，携带两种商品：鱼子酱和蜂蜜。 最初，他拥有固定数量的每种商品，并且每个单位随后可以以已知价格出售。 他的最终利润取决于每种商品在城市市场上能存活多少，因为所有不用于通行费的东西都可以出售。 

途中，他必须经过一个海关检查站。 到了这个检查站，他被强制交过路费，但是他可以灵活选择如何交费。 他可以支付固定金额，也可以用一定量的鱼子酱或一定量的蜂蜜代替付款。 每个选项完全替代相同的通行费，但消耗不同的资源。 

目标是选择一种付款方式，在出售剩余商品并计算通行费支付的任何现金后，使最终货币收益最大化。 

关键结构是只有一个决策点：如何支付单一通行费。 此后，一切都是线性的，因为剩余的商品以固定价格独立出售。 

尽管约束条件包括非常大的商品数量（高达数千万），但只有恒定数量的有意义的策略需要评估，因此解决方案必须避免对数量进行任何模拟。 

一个常见的错误是假设您应该始终最大限度地减少通行费的直接成本。 但这是失败的，因为支付货物会消除未来的销售利润，而不仅仅是直接价值。 

例如，如果鱼子酱与蜂蜜相比非常有价值，那么即使避免花费现金，就收入损失而言，用鱼子酱付款可能要贵得多。 

另一个微妙的边缘情况是支付方式的可行性。 如果商家没有足够的鱼子酱或蜂蜜，这些选项就无效，即使它们在价值方面看起来是最优的。 

## 方法

 暴力思维是考虑使用不同数量的商品和现金支付通行费的所有可能组合。 然而，该问题不允许部分付款，并且通行费以三种离散形式固定。 这将决策空间折叠成最多三个候选策略。 

正确的见解是，整个优化是针对收费站本地的。 收费之前和之后的一切都与剩余资源呈线性关系，因此收费的唯一效果是从固定初始值中一次性减去。 这使我们能够通过计算应用后的最终利润来独立评估每个付款选项。 

对于每个选项，我们计算剩余的鱼子酱和蜂蜜，使用给定的价格将它们转换为货币，并减去支付的现金（如果适用）。 有效选项中最好的结果就是答案。

 ## 算法演练

 我们通过直接评估三种可能的收费方式来计算结果。

1. 首先计算不支付现金通行费的基准利润：总价值为 i·a + m·b。 这代表应用任何约束之前的最大理论收入。 
2. 考虑用现金v支付通行费。此时，在检查站没有消耗任何商品，因此剩余价值为i·a + m·b − v。 
3.考虑使用c克鱼子酱来支付通行费。 该选项仅在 i ≥ c 时有效。 如果有效，则剩余货物为(i − c, m)，因此利润变为(i − c)·a + m·b。 该模型模拟了被移除的鱼子酱未来销售价值的损失。 
4.考虑使用d克蜂蜜来支付通行费。 该选项仅在 m ≥ d 时有效。 如果有效，则剩余货物为(i, m − d)，因此利润变为i·a + (m − d)·b。 
5. 取所有有效选项中的最大值。 

为什么它有效

 每个支付选项对应于剩余资源的不同最终状态。 检查点之后，收入完全由剩余商品的线性估值决定。 由于鱼子酱和蜂蜜之间除了收费处的单一减法之外没有任何相互作用，因此最佳策略必须是这三个端点之一。 任何假设的混合策略都会与收费的固定形式性质相矛盾，这种性质强制要求在三个离散转换之间进行单一选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    i, m, a, b, v, c, d = map(int, input().split())

    base = i * a + m * b
    ans = base - v  # pay money

    if i >= c:
        ans = max(ans, (i - c) * a + m * b)

    if m >= d:
        ans = max(ans, i * a + (m - d) * b)

    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先计算商品的全部价值，不进行任何扣除。 这可以作为所有其他结果的参考点。 现金支付情况直接减去v即可处理。 

然后我们检查每个基于货物的支付的可行性。 每次检查只是确保存在足够的库存，然后在删除相应数量后重新计算结果值。 不需要模拟，因为只发生一次推论。 

比较是逐步进行的，因此我们始终保留可实现的最佳结果。

 ## 边缘情况

 一种极端情况是，现金支付看起来很有吸引力，因为它可以避免损失货物，但实际上比出售货物所减少的最终利润更多。 例如，如果 a 很大，即使是很小的鱼子酱折扣也可能比支付现金更有价值。 

另一种情况是基于商品的支付几乎不可行。 如果 i 恰好等于 c，则剩余的鱼子酱将变为零，这会极大地改变价值。 该算法处理这个问题是因为它在计算简化状态之前检查 i ≥ c。 

第三种情况是两次货款均无效。 在这种情况下，只剩下现金支付，并且算法正确地回退到基数-v，而不比较无效状态。
