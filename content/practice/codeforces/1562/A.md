 ## 解决方案
 ## 问题理解

 该任务要求我们在给定一系列整数的情况下，最大化一个整数除另一个整数时的余数。 具体来说，我们有两个整数，`l`和`r`，我们可以选择任意一对`(a, b)`这样`b`至少是`l`并且至多`a`， 和`a`至多是`r`。 输出应该是最大可能的值`a % b`。 从概念上讲，这就像问：如果我们可以在给定的区间内选取两个数字，我们如何才能使余数尽可能大？ 

约束条件告诉我们`l`和`r`每个最多可以达到 10 亿个，我们可能有多达 10,000 个测试用例。 任何尝试所有可能对的解决方案`(a, b)`大约需要`(r-l+1)^2`每个测试用例的操作，这是远远超出可行的，因为`(10^9)^2`是一个天文数字。 因此，我们需要一个在每个测试用例中以恒定或对数时间运行的解决方案。 

非明显的边缘情况包括`l`等于`r`。 例如，如果`l = r = 1`，唯一有效的对是`(1, 1)`，所以余数为`0`。 另一个微妙的情况是当`r`仅略大于`l`， 例如`l = 999999999`和`r = 1000000000`。 粗心的实现可能会尝试减去`l`从`r`并假设结果总是小于`b`，但这种情况下的最大余数实际上是`r - l`，而不是一些较小的数字。 

## 方法

 暴力方法很简单。 迭代所有可能的情况`b`从`l`到`r`，那么对于每个`b`, 迭代所有`a`从`b`到`r`, 计算`a % b`每次并记录最大值。 这是有效的，因为我们明确检查每个可能的对，确保正确性。 问题是效率：在最坏的情况下，`r - l`几乎是`10^9`，所以操作次数大致为`(r-l+1)*(r-l+1)`每个测试用例，这是完全不可行的。 

最佳解决方案的关键是理解模运算的行为。 剩下的`a % b`总是小于`b`，并且达到最大值，`b-1`， 什么时候`a`刚好低于`b`。 因为我们想要一些最大的余数`b`在`[l, r]`，最优选择为`b`接近一半`r`。 具体来说，如果我们采取`b = floor((r+1)/2)`，那么最大的`a % b`我们可以得到的是`b-1`，只要这个`b`是在`[l, r]`。 如果`b`小于`l`，那么最大余数就是`r - l`，这发生在`a = r`和`b = l`。 这将问题简化为每个测试用例的简单计算，完全避免了循环。

 | 蛮力 | O((r-l+1)^2) | O((r-l+1)^2) | O(1) | O(1) | 太慢了|

 ## 算法演练

 1. 对于每个测试用例，读取整数`l`和`r`。 
2. 计算`mid = (r + 1) // 2`。 这代表最小的`b`这样我们就可以得到接近于`b-1`。 
3.如果`mid`至少是`l`，则最大余数为`r % mid`。 这是因为`r`是最大可能的`a`，并取模`mid`给出尽可能接近的余数`mid - 1`。 
4. 如果`mid`小于`l`， 然后`l`太大，不允许有接近的余数`b-1`，所以我们能做的就是`r - l`。 
5. 打印计算出的最大余数。 

这有效是因为`a % b`总是小于`b`，所以最大的`b`仍然允许余数接近`b-1`大约是一半`r`。 通过采取`a = r`和`b = mid`，我们保证在给定约束的情况下余数最大化。 如果`mid`小于`l`，然后选择`b = l`和`a = r`给出该情况下最大可能的余数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    l, r = map(int, input().split())
    mid = (r + 1) // 2
    if mid >= l:
        print(r % mid)
    else:
        print(r - l)
```该代码首先读取测试用例的数量，然后循环遍历每个测试用例。 它计算`mid`作为`(r+1)//2`找到最大的`b`这允许高剩余。 如果`mid`是有效的（至少`l`),`r % mid`是最大模数。 否则，最大余数出现在`r - l`。 整数除法确保我们正确处理偶数和奇数`r`。

 ## 边缘情况

 当`l = r = 1`，算法计算`mid = 1`，等于`l`， 所以`r % mid = 1 % 1 = 0`。 这可以正确处理单值区间。 什么时候`r - l = 1`， 例如`l = 999999999`和`r = 1000000000`,`mid = 500000000`，大于`l`， 所以`r % mid = 1000000000 % 500000000 = 0`，但是选择`b = l`会给`r - l = 1`，更大。 条件正确地处理了这个问题，在所有边缘场景中给出了最佳的余数。
