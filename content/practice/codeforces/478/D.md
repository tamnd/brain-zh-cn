 ## 解决方案
 ## 问题理解

 我们被要求建造一个由两种类型的块（红色和绿色）制成的楼梯状结构。 该结构具有一定数量的级别，并且级别在大小上形成严格的递减序列：如果顶层有大小`n`，那么下一个有`n-1`， 然后`n-2`，依此类推直至`1`。 

每个级别必须是单色的，这意味着每个级别都是全红色或全绿色，但不同级别可以独立选择其颜色。 一旦我们选择了高度，使用的块总数就固定了`n`，因为结构总是使用三角数`n(n+1)/2`块。 

第一个任务是确定最大可能高度`h`使得所需的区块总数不超过可用供应量`r`红色和`g`绿色块组合在一起。 确定这个高度后，我们必须计算有多少个有效颜色`h`级别的存在使得我们可以为每个级别分配一种颜色，并且永远不会超过红色或绿色块的可用数量。 

关键的困难在于，限制不仅仅是总使用量，而是按颜色划分不同大小的级别。 仅检查总块的简单方法忽略了颜色分配的可行性。 

限制允许每种颜色最多 200,000 个块。 对所有级别颜色分配的直接枚举是指数级的`h`，因为每个级别都是二元选择。 这立即排除了对所有任务的暴力破解。 我们需要一种压缩指数决策空间的动态规划方法。 

当一种颜色为零时，就会出现边缘情况。 如果`r = 0`，那么所有级别都必须是绿色的，并且只有在三角形和适合的情况下我们才能构建最大高度`g`。 在这种情况下，答案是 1 或 0，具体取决于可行性。 对称论证成立`g = 0`。 另一个微妙的情况是当最大高度很小但两个资源都很大时，这使得计数维度成为主导部分。 

## 方法

 直接的方法是首先计算最大可能高度`h`。 由于每个级别都会增加`i`水平块`i`，总共需要的是`h(h+1)/2`。 我们增加`h`直到这个总和超过`r + g`。 这部分很简单。 

真正的复杂性来自于计算这些颜色分配`h`水平。 每个级别`i`可以是红色或绿色。 如果一个级别是红色的，则它会消耗`i`红色块； 如果是绿色的，它会消耗`i`绿色块。 我们必须确保红色的总用量不超过`r`，总绿地使用量不超过`g`。 

暴力解决方案会尝试所有`2^h`分配任务并检查可行性。 这仅适用于非常小的`h`。 为了`h`大约 200,000 个（尽管实际上由于三角形增长而要小得多），这是不可能的。 

关键的观察是，我们实际上不需要完全详细地对称地跟踪两种颜色。 如果我们决定哪个级别子集为红色，则自动确定绿色。 问题变成：计算子集`{1,2,...,h}`其总和最多为`r`，而补集之和最多为`g`。 

令总和为`S = h(h+1)/2`。 如果子集总和为`x`，然后红色使用`x`和绿色利用`S-x`。 所以我们需要：`x ≤ r`和`S - x ≤ g`，这相当于：`S - g ≤ x ≤ r`。 

所以问题简化为计算子集和`{1..h}`落在有界区间内。 

我们定义一个DP，其中`dp[i][j]`是首先选择的方式数量`i`水平使得所选的红色总和恰好是`j`。 每个级别`i`要么变成红色（添加`i`）或绿色（不向红色总和添加任何内容）。 这是一个经典的背包式过渡。 

我们只需要 DP 达到`r`，我们总结有效的`j`在`[S-g, r]`。 

这将指数分配空间减少为总和值上的多项式 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解关卡 | O(2^h) | O(2^h) | O(h) | 太慢了 |
 | 子集和上的 DP | O(h·r) | O(r) | 已接受 |

 ## 算法演练

 1.计算最大高度`h`这样`h(h+1)/2 ≤ r + g`。 这固定了总结构尺寸。 原因是任何有效的塔都必须适合总可用块，无论颜色分割如何。 
2. 计算所需的总块数`S = h(h+1)/2`。 这让我们可以将两个资源约束转换为红色使用的单个间隔约束。 
3. 推导红色使用的有效范围为`[L, R] = [S - g, r]`。 任何红色级别的分配都必须落在该范围内，否则超出绿色或红色容量。 
4. 初始化一个DP数组`dp`尺寸的`r + 1`， 在哪里`dp[j]`代表实现红和的方法数`j`使用经过处理的级别。 
5. 设置`dp[0] = 1`，因为不选择红色级别会产生总和为零。 
6. 迭代级别`1`到`h`。 对于每个级别`i`，以相反的顺序更新DP`r`下降到`i`。 这确保每个级别最多使用一次。 
7. 对于每个可达到的总和`j`，传播转换：要么保持水平`i`绿色（不执行任何操作），或将其分配为红色并将贡献从`dp[j - i]`到`dp[j]`。 
8.处理完所有级别后，将所有级别求和`dp[j]`为了`j`在`[L, R]`。 这会聚合所有有效配置。 

### 为什么它有效

 每个级别都独立分配为红色或绿色。 仅编码红色水平就足够了，因为绿色是由补体决定的。 DP 通过子集和构造确保级别的每个子集都被精确计数一次。 间隔约束同时强制执行两种颜色的可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    r, g = map(int, input().split())

    # find maximum height h such that h(h+1)/2 <= r+g
    total = r + g
    h = 0
    while (h + 1) * (h + 2) // 2 <= total:
        h += 1

    S = h * (h + 1) // 2

    L = max(0, S - g)
    R = min(S, r)

    if L > R:
        print(0)
        return

    dp = [0] * (r + 1)
    dp[0] = 1

    for i in range(1, h + 1):
        for j in range(r, i - 1, -1):
            dp[j] = (dp[j] + dp[j - i]) % MOD

    ans = sum(dp[L:R+1]) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```代码首先使用三角形增长确定可行的高度。 然后，它将问题转化为级别大小上的子集和 DP。 DP 循环中的反向迭代对于避免多次重复使用同一级别至关重要。 最后的求和步骤强制执行从二色约束导出的有效红色范围。 

一个常见的实现错误是忘记约束不仅是总和，而且是子集和的有界区间。 另一个是向前迭代 DP 而不是向后迭代，这会错误地允许多次重复使用同一级别。 

## 工作示例

 ### 示例 1

 输入：```
4 6
```这里可用块的总数是 10。最大的`h`和`h(h+1)/2 ≤ 10`是`h = 4`，因为 4·5/2 = 10。 

所以水平是`{1,2,3,4}`, 总和`S = 10`。 

有效的红色总和必须满足`S - g ≤ x ≤ r`， 所以`10 - 6 ≤ x ≤ 4`， IE。`4 ≤ x ≤ 4`。 所以红色总和一定是 4。 

我们计算子集和`{1,2,3,4}`等于 4。这些是`{4}`和`{1,3}`。 

| 水平| 行动| dp 状态（非零条目）|
 | --- | --- | --- |
 | 0 | 初始化| {0:1} |
 | 1 | 添加 1 | {0:1, 1:1} |
 | 2 | 添加 2 | {0:1, 1:1, 2:1, 3:1} |
 | 3 | 添加 3 | {0:1, 1:1, 2:1, 3:2, 4:1, 5:1, 6:1} |
 | 4 | 添加 4 | {4:2, ...} |

 最终答案是2。 

此跟踪显示 DP 正确计算了不同子集，从而产生有效的红色分配。 

### 示例 2

 输入：```
3 3
```总数为 6，所以最多`h = 3`，因为 3·4/2 = 6。 

我们需要红色金额`[6-3, 3] = [3,3]`，所以正好是 3。 

的子集`{1,2,3}`总和为 3`{3}`和`{1,2}`。 

DP 将精确地以两种方式累加，以确认正确性。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(h·r) | 每个级别都会更新所有红色容量的背包 DP |
 | 空间| O(r) | 存储子集总和计数的单个数组 |

 高度`h`大致增长为`O(sqrt(r+g))`，因此 DP 在 200k 约束下保持高效。 由于与原始输入尺寸相比三角形高度相对较小，因此该解决方案可以轻松地满足限制。

 ## 边缘情况

 当一个资源为零时，当且仅当完全三角和拟合时，DP 才会退化为单个有效配置。 该算法自然地处理了这一问题，因为有效区间会压缩为单个值，并且只有一个子集和可以匹配它。 

什么时候`r + g`由于大到足以形成一个非常小的塔，DP 运行的层数非常少。 子集和结构确保即使是很小的实例也可以在没有特殊大小写的情况下进行处理。 

什么时候`r`远大于`g`, 有效区间`[S-g, r]`可能从零以上开始，这会过滤掉许多 DP 状态。 求和步骤确保仅计算可行的配置，避免过度计算超出绿色容量的子集。
