 ## 解决方案
 ## 问题理解

 我们有三种类型的气球：红色、绿色和蓝色。 宴会上每桌需要正好三个气球，并且任何一桌都不可能拥有所有三个相同颜色的气球。 任务是计算在给定一定数量的红色、绿色和蓝色气球的情况下我们可以装饰的桌子的最大数量。 

输入由三个整数组成，表示每种颜色的气球数量。 输出是一个整数：满足约束的表的最大数量。 气球计数的界限高达 2×10^9，这意味着我们无法负担任何迭代所有可能组合的算法。 我们需要一个相对于输入值在基本恒定的时间内运行的解决方案。 

一种简单的方法可能会尝试减少循环中的计数，始终从每种可用颜色中取出一个气球。 当一种颜色占主导地位时，这种方法会失败：如果我们有比绿色和蓝色更多的红色气球，那么总是采用每种颜色之一的简单贪婪方法可能会留下未使用的红色气球，这些气球本来可以更有效地配对。 一个例子是有 10 个红色、1 个绿色和 1 个蓝色气球。 天真地采用每种颜色中的一种只会产生一张表格，但我们不能制作更多表格，因为我们必须避免重复所有相同的颜色。 正确的输出确实是 1，但是对于稍微平衡的数字，贪心选择可能会变得不明显，因此算法必须推理相对大小。 

另一个潜在的陷阱是依赖于气球总和的整数除以 3。 虽然最大表数不能超过`(r + g + b) // 3`，这只是一个上限。 粗心的方法可能会直接返回该值，而不考虑各个颜色限制。 

## 方法

 蛮力方法是重复选择三个气球，同时确保它们的颜色不同。 在实践中，我们会选择三个最大的计数并逐个递减。 虽然这保证了正确性，但在最坏的情况下，如果所有计数都很大，则可能需要最多 2×10^9 次迭代。 显然，迭代这么多次是不可行的。 

最佳解决方案的关键观察是问题受到气球总数和最大单个颜色的限制。 每张桌子需要三个气球，因此桌子的最大数量最多为`(r + g + b) // 3`。 另一方面，如果一种颜色的数量大于其他两种颜色的总和，则多余的气球无法配对形成表格，因此表格的有效数量也受到两种较小颜色的总和的限制。 因此，真正的最大表数是这两个数量中的最小值：`(r + g + b) // 3`和`r + g + b - max(r, g, b)`（相当于两个较小数字的总和）。 这确保了我们永远不会尝试过度分配主色或违反每个表的颜色规则。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(最大(r, g, b)) | O(1) | O(1) | 太慢了 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.将红、绿、蓝气球的计数读入变量`r`,`g`， 和`b`。 这为我们提供了可用的全部资源。 
2. 计算所有气球的总和。 如果颜色完美平衡，则使用整数除法将此总和除以三即可获得理论最大表格数。 将其存储为`max_by_total`。 这确保我们永远不会超过可用气球的总数。 
3. 找出三种颜色中气球数量最多的。 两个较小计数的总和是我们在不违反每个表颜色限制的情况下实际可以形成的表的最大数量。 将其存储为`max_by_balance`。 
4.答案是最小的`max_by_total`和`max_by_balance`。 这保证了我们尊重总气球限制和分布约束。 

为什么它有效：该算法维护两个不变量。 第一的，`(r + g + b) // 3`确保我们制作的桌子数量不会超过气球总数所允许的数量。 其次，两个较小计数的总和确保没有表最终会出现三种相同的颜色。 因为每张桌子都会从某种组合中的三种颜色中删除一个气球，所以这个界限捕获了所有可行的排列。 采取最低限度的保证，我们同时尊重这两个约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

r, g, b = map(int, input().split())

total = r + g + b
max_total_tables = total // 3
max_by_balance = total - max(r, g, b)

print(min(max_total_tables, max_by_balance))
```该代码首先使用以下方法有效读取三个整数`sys.stdin.readline`。 它计算气球的总数并除以三得出​​理论上限。 然后计算两个较小计数的总和：`total - max(r, g, b)`，相当于将其他两种颜色相加。 最后，它打印两个边界的最小值以遵守这两个约束。 使用减法代替排序是一种微妙的优化，可以避免不必要的操作。

 ## 边缘情况

 用于输入`10 1 1`，总和除以 3 得到 4，但最大的颜色是 10，而其他两个的总和是 2。该算法计算`total - max(r, g, b) = 12 - 10 = 2`，正确地将表限制为 2。对于输入`0 0 0`， 两个都`total // 3`和`total - max(...)`产量 0，正确生成零表。 在所有计数相等的情况下，将总和除以 3，然后`total - max(...)`产生相同的数字，确保不会发生相差一的错误。 这表明该方法可以正确处理极端不平衡和完美平衡的输入。
