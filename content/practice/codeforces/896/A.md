 ## 解决方案
 ## 问题理解

 此问题中的构造会生成一系列字符串，其中每个级别将前一个级别包装在固定模板内。 基本字符串，称之为$f_0$, 是固定句。 每个下一个字符串$f_i$通过采用固定的外部句型并插入整个先前的字符串来形成$f_{i-1}$两次：一次在“发送时”等短语之后，一次在“发送”等另一个短语内。 

因此，每个级别并不会创建通常意义上的新“内容”，它只是通过多次嵌入前一个字符串来增加嵌套深度。 结果，字符串的长度增长得非常快，远远超出了可以显式构造的大型字符串的长度。$n$。 任务不是构建这些字符串，而是回答以下形式的查询：“什么是$k$第 - 个字符$f_n$?”，或者如果该位置不存在则报告占位符。

 输入大小立即排除任何显式构造。 深度$n$可以达到$10^5$，以及位置$k$可以大到$10^{18}$。 即使存储单个$f_n$是不可能的，因为长度相对于$n$。 直接模拟所需的时间与所得字符串的大小成正比，即使对于较小的字符串，该时间也会变得天文数字般大。$n$。 

唯一可行的方向是从结构上推理如何定位$f_n$映射回位置$f_{n-1}$。 由于每个字符串都由固定文本加上前一层的两个嵌入副本组成，因此我们可以将其构造视为间隔的递归树。 

当出现一个微妙的问题时$k$超过长度$f_n$。 由于长度迅速爆炸，但对于固定的来说仍然是有限的$n$，我们必须在预处理期间限制值。 另一个边缘情况是基本字符串已经包含空格和标点符号，因此索引必须是字符精确的，并且不假设单词边界。 

一个天真的错误是尝试实际构建字符串，直到它们超过$k$。 这失败了，因为对于中等$n$，长度早在达到之前就已经超出了内存限制$10^{18}$，即使只有长度被错误地跟踪而没有边界。 

## 方法

 蛮力方法实际上会构建每个$f_i$通过连接字符串。 每一步都会将前一个字符串的大小加倍，再加上恒定的前缀和后缀。 即使忽略恒定的开销，这也会产生指数增长，并且构建最多$f_{10^5}$是不可能的。 即使计算单个大$f_n$对于中等程度的$n$几乎立即在记忆中变得不可行。 

关键的观察是我们永远不需要完整的字符串，只需要它的长度和将位置映射回子问题的能力。 每个$f_i$由三个结构部分组成：固定前缀、嵌入$f_{i-1}$，另一个固定的中间段，另一个嵌入的$f_{i-1}$，和一个固定后缀。 这意味着任何索引$k$位于固定部分之一或递归副本之一内。 

我们不是构建字符串，而是预先计算所有字符串的长度$f_i$最多$n$，但上限为$10^{18}$因为任何更大的东西都与查询无关。 然后每个查询都通过从$f_n$到$f_0$，反复判断哪个段包含位置$k$。 每当我们进入递归段时，我们都会翻译$k$进入对应的索引里面$f_{i-1}$并继续。 

这将指数构造转换为对数下降$n$，每个查询变成$O(n)$，这是可以接受的，因为$n \le 10^5$但无论什么时候我们都会提前停下来$k$落入固定字符串或出界。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力建设| 指数| 指数| 太慢了|
 | 长度 DP + 递归下降 |$O(n)$每个查询 |$O(n)$| 已接受 |

 ## 算法演练

 我们首先形式化每个字符串的结构。 每个级别$f_i$包括：

 1.固定前缀字符串$A =$“发送时你在做什么”。 
2、整体$f_{i-1}$。 
3.固定中弦$B =$”？你忙吗？你会发“”。
 4.另一份$f_{i-1}$。 
5.固定后缀$C =$“”？”。

 这些组件的结构是线性的，因此我们只跟踪长度。 

1. 预先计算长度$f_i$从$i = 0$到$n$，停止增长$10^{18}$。 这可以避免溢出并在处理大型数据时保持比较安全$k$。 
2. 对于每个查询$(n, k)$，检查是否$k$超过总长度$f_n$。 如果是，则返回“.” 立即，因为该职位不存在。 
3. 否则，模拟从水平面开始下降$n$。 在每个级别$i$， 比较$k$按顺序对照五个结构件的长度。 
4. 如果$k$落在固定段内$A, B, C$，直接返回相应的字符，因为这些字符串是常量。 
5. 如果$k$属于第一个或第二个副本$f_{i-1}$，减去所有先前段的偏移量并继续在该级别递归$i-1$。 
6. 重复直到达到$f_0$，直接得到答案。 

这样做的原因是每个位置$f_i$恰好属于一个不相交的段：要么是固定文本，要么是两个相同的递归子结构之一。 映射来自$f_i$到$f_{i-1}$保留相对顺序，因此减去偏移量可以正确地将全局索引转换为局部索引。 

不变量是在每个递归步骤中，对$(i, k)$始终引用概念字符串中的相同字符$f_i$。 该算法永远不会跳过或重复区域，因为分段在每个级别都完全划分了字符串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    base = "What are you doing at the end of the world? Are you busy? Will you save us?"
    A = "What are you doing while sending "
    B = "? Are you busy? Will you send \""
    C = "\"?"

    q = int(input().strip())
    queries = [tuple(map(int, input().split())) for _ in range(q)]

    MAX = 10**18

    # precompute lengths
    # f0
    f_len = [0] * (100005)
    f_len[0] = len(base)

    for i in range(1, 100005):
        val = len(A) + len(B) + len(C)
        if f_len[i - 1] > MAX:
            inner = MAX
        else:
            inner = f_len[i - 1]

        val += 2 * inner
        f_len[i] = min(MAX, val)

    def get_char(n, k):
        if n == 0:
            return base[k - 1] if 1 <= k <= len(base) else '.'

        A_len = len(A)
        B_len = len(B)
        C_len = len(C)
        inner = f_len[n - 1]

        if k <= A_len:
            return A[k - 1]

        k -= A_len

        if k <= inner:
            return get_char(n - 1, k)

        k -= inner

        if k <= B_len:
            return B[k - 1]

        k -= B_len

        if k <= inner:
            return get_char(n - 1, k)

        k -= inner

        if k <= C_len:
            return C[k - 1]

        return '.'

    for n, k in queries:
        print(get_char(n, k), end='')

if __name__ == "__main__":
    solve()
```解决方案首先修复所有常量片段。 长度数组至关重要，因为它可以防止溢出：一旦级别超过$10^{18}$，我们将其视为饱和，因为任何查询$k$无法有意义地区分更大的值。 

递归函数`get_char`执行结构下降。 每次减去线段长度都会将坐标系移动到正确的子部分。 当输入递归副本时$f_{n-1}$，我们直接传递调整后的索引，保持正确性而不重新计算绝对位置。 

一个常见的实现陷阱是忘记限制长度，这会导致溢出和不正确的比较$k$很大。 另一个问题是在 1 索引查询位置和 0 索引 Python 字符串之间切换时出现差一错误。 该代码始终使用以下方式进行转换`k - 1`仅在直接字符串访问时。

 ## 边缘情况

 当出现临界边缘情况时$k$大于全长$f_n$。 在这种情况下，算法立即返回“.”，避免任何递归。 例如，如果$n = 2$和$k = 10^{18}$，预先计算的长度已经达到上限$10^{18}$，并且比较提前失败。 

另一个边缘情况是当$n = 0$。 该算法必须直接索引到基本字符串，而不尝试进行结构分解。 这是在递归基本情况中明确处理的。 

第三种边缘情况是当$k$正好落在段之间的边界上，例如递归块的最后一个字符。 由于所有段边界都是使用严格的不等式计算的，因此每个位置恰好属于一个段，从而确保递归链上的确定性路由。
