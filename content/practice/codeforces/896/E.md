 ## 解决方案

 ## 问题理解

 我们维护一个正整数数组，该数组在两种类型的范围运算下随时间变化。 每个元素代表剩余的“烘焙时间”，操作要么减少一些值，要么询问有多少元素与确切的目标值匹配。 

第一个操作需要一个段和一个阈值 x，对于该段中的每个位置，如果当前值大于 x，我们从中减去 x。 最多已经为 x 的值保持不变。 第二个操作再次在一个段上询问此时有多少个值恰好等于 x。 

困难在于，这两个操作都是基于范围的，并且数量最多为 100000 个，值和数组大小也最多为 100000 个。为每个查询扫描整个段的简单模拟将降级为 O(nm)，这远远超出了可接受的范围，可能需要大约 10^10 次操作。 

一个更微妙的问题是，价值会以结构化的方式减少。 它们永远不会增加，并且每次更新只会将值减少相同的 x，但前提是它们高于 x。 这会产生重复的“裁剪”行为，这种行为不是统一的减法，这使得典型的线段树延迟传播对加法毫无用处。 

打破天真的推理的边缘情况包括：

 所有值都略高于 x 的段。 例如，a = [10, 11, 12]，x = 5 的运算 1 将其转换为 [5, 6, 7]。 一个幼稚的错误是从所有元素中减去 x，在这里正确生成 [5, 6, 7]，但在某些元素已经 ≤ x 的情况下，例如 [3, 11, 12]，错误地从所有元素中减去 x 会产生负值或错误值，例如 [−2, 6, 7] 而不是 [3, 6, 7]。 

另一个微妙的情况是重复更新，其中值跨越多个阈值。 例如，重复减法可能会导致一个值在一次操作后降至 x 以下，然后在以后的操作中保持不变，这使得任何假设跨段单调均匀变化的方法都无效。 

## 方法

 蛮力的想法很简单。 对于每个更新或查询，我们迭代范围 [l, r]。 对于类型 1 运算，我们检查每个值，如果大于 x，则减去 x。 对于类型 2，我们计算有多少个值等于 x。 

这是正确的，因为它直接遵循定义。 然而，在最坏的情况下，每个操作的成本为 O(n)，从而导致 O(nm)。 当 n 和 m 达到 10^5 时，这速度太慢了几个数量级。 

关键的观察是值在更新时不会任意表现。 它们只会减少，更重要的是，每当 a[i] 值大于 x 时，在重复应用类似操作后，它实际上会变成 a[i] mod x。 “大于 x 时减去 x”操作一次应用后正好是 a[i] = a[i] % x，因为它将值减小到范围 [1, x] 内。 

这将问题转化为跟踪段，其中值要么不变，要么减少为更小的等价类。 不相交集联合结构可用于跳过在给定操作下不再改变的位置。 一旦仓位的价值≤x，以后x较大的操作就不会影响它。 这使我们能够在指数结算时将其从积极考虑中“删除”。 

我们在索引上维护类似 DSU 的下一个指针结构。 当索引 i 被处理并且其值在未来操作中变得稳定时，我们将其向前合并，这样我们就不会再次重新访问它以进行类似的更新。 这确保了每个索引在所有操作中仅被有效访问对数次数。

对于类型 2 查询，我们无法扫描段。 相反，我们维护基于值的结构，允许计算范围内精确值的出现次数。 标准解决方案使用 Fenwick 树或每个值桶的有序结构，但在这种基于 DSU 的方法中，我们在修改值和查询前缀和时更新计数。 

跳过已经稳定的索引和维护频率结构的组合将复杂性降低到接近 O((n + m) log n)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了|
 | DSU+频率跟踪| O((n + m) log n) | O((n + m) log n) | O(n) | 已接受 |

 ## 算法演练

 我们维护三个核心思想：DSU“下一个活动索引”结构、当前值数组和用于计数出现次数的频率结构。 

1. 初始化一个数组parent，其中parent[i] = i + 1。这允许我们跳过已完全处理的索引。 DSU 确保我们始终跳转到范围中的下一个候选索引。 
2. 在值上构建频率结构，通常是按值索引的 Fenwick 树，存储每个值出现的次数。 这样可以有效地对精确值进行范围计数。 
3. 对于带有参数 x 的 [l, r] 上的类型 1 操作，我们从 find(l) 开始迭代 i，使用 DSU 跳转，并在 i 超过 r 时停止。 这可以避免触及已经处理过的超出此范围的索引。 
4. 对于每个访问过的索引 i，如果 a[i] ≤ x，我们将其保持不变并移至下一个索引。 原因是不满足还原条件。 
5. 如果 a[i] > x，我们从频率结构中删除其旧值，将其更新为 a[i] − x，然后插入新值。 然后我们继续前进。 
6. 如果更新后该值变得足够小，以至于永远不会受到类似性质的未来操作的影响，我们会在 DSU 中将 i 与 i + 1 合并，以便将来的扫描跳过它。 这是保证摊余效率的机制。 
7. 对于类型 2 操作，我们查询频率结构以了解 [l, r] 内有多少个元素等于 x。 这是通过前缀计数完成的。 

### 为什么它有效

 每个指数都只是“活跃”的，但仍可以通过未来的操作来减少。 一旦它在 DSU 跳过规则下变得稳定，就不再被处理。 由于每次更新都会严格减少值，并且每个索引在变得稳定之前只能转换有限的次数，因此我们接触任何索引的总次数是有界的。 频率结构保持正确，因为每次修改都与删除和插入配对，从而保持全局一致性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    n, m = map(int, input().split())
    a = [0] + list(map(int, input().split()))
    MAXV = 100000

    bit = Fenwick(MAXV)

    for i in range(1, n + 1):
        bit.add(a[i], 1)

    parent = list(range(n + 2))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(x, y):
        x = find(x)
        y = find(y)
        if x != y:
            parent[x] = y

    def process(l, r, x):
        i = find(l)
        while i <= r:
            if a[i] <= x:
                i = find(i + 1)
                continue
            bit.add(a[i], -1)
            a[i] -= x
            bit.add(a[i], 1)
            if i < n:
                union(i, i + 1)
            i = find(i + 1)

    for _ in range(m):
        tmp = input().split()
        if tmp[0] == '1':
            _, l, r, x = map(int, tmp)
            process(l, r, x)
        else:
            _, l, r, x = map(int, tmp)
            ans = bit.range_sum(x, x)
            print(ans)

solve()
```Fenwick 树跟踪值的全局频率，这已经足够了，因为类型 2 查询要求精确的值计数。 每次更新都会删除旧值并插入新值，以保持一致性。 

DSU 结构确保在范围更新期间我们跳过不再需要处理的索引，这是避免每次查询 O(n) 的关键。 

一个微妙的点是合并发生在更新值之后。 这很重要，因为一旦索引变得足够小，它应该立即变得有资格跳过，否则会发生重复访问。

 ## 边缘情况

 一个关键的边缘情况是当一个值反复变得可以精确整除为小值时。 例如，从 10 开始并重复应用 x = 3 会产生 7、4、1，然后不再进行任何更改。 一种幼稚的方法可能会重复地重新访问相同的索引，但 DSU 确保一旦它在某种条件下变得稳定，它就会在以后的遍历中完全跳过。 

另一种情况是当查询请求一个仅在一系列归约之后出现的值时。 Fenwick 更新可确保立即反映每个中间值转换，因此即使值在范围内“移动”，计数也能保持准确。
