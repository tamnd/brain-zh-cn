 ## 解决方案

 ## 问题理解

 我们正在计算有多少种方式可以安排顾客排队，使电影院收银员永远不会用完零钱，并且在为每个人服务后，剩余的 50 元纸币数量落在给定的区间内。 

每个客户独立地属于三种类型之一。 其中一种带有 50 元纸币，可增加 1 个单位的零钱。 一类自带100元纸币，付款时会消耗一张之前收集的50元纸币，并且只有当时有50元纸币可用时才有效。 最后一种是VIP，既不给予也不消耗零钱，可以出现在任何地方，不影响可行性。 

这个过程是顺序的：顾客的顺序很重要，在队列的每个前缀处，100元顾客的数量不能超过迄今为止出现的50元顾客的数量。 处理完所有 n 个客户后，我们计算 50 元纸币的最终剩余，并且只计算最终值位于 [l, r] 的排列。 

这些约束将其推入组合计数机制而不是模拟。 当 n 达到 100000 时，任何枚举排列甚至跟踪所有序列的完整状态的方法都是不可能的。 答案必须来自结构化路径上的封闭形式计数参数或来自具有前缀可行性约束的多项式式聚合。 

微妙的边缘情况来自可行性和最终平衡之间的相互作用。 例如，如果我们忽略前缀有效性，则像“B B A”(100, 100, 50) 这样的序列可能会被错误地计数，即使它从一开始就是无效的，因为无法为第一个客户提供服务。 另一个边缘情况来自 VIP 客户：它们不会影响平衡，但确实会影响订购多样性，任何过早崩溃的方法都有可能失去组合因素。 

## 方法

 直接的强力解决方案将生成所有 3^n 个序列并模拟每个序列的收银流程。 对于每个序列，我们跟踪一个余额计数器，该计数器在 50 元客户上增加，在 100 元客户上减少，拒绝任何使余额为负的序列。 完成后，我们检查最终余额是否在[l,r]中。 这是正确的，但它探索了 3^n 种可能性，即使进行修剪，仍然以 n 为指数，这使得它在非常小的输入之外不可行。 

关键的结构观察是 VIP 客户是中立的：他们不影响可行性，只影响安置。 这表明将问题分为两层。 首先选择VIP的位置，然后用相当于选票问题的前缀约束来计算仅由A（50元）和B（100元）组成的剩余位置的有效序列。 最终的余额仅取决于 A 和 B 的计数之差，而 VIP 则以组合方式相乘。 

一旦简化为A和B序列，可行性条件正是经典条件，即在每个前缀处，A计数至少是B计数。 这是 Dyck 路径的变体。 具有固定数量的 A 和 B 的有效序列的数量由加泰罗尼亚风格的投票公式给出。 然后，我们将 VIP 分配到 n 个位置，并对所有可能的计数进行求和，与 [l, r] 中的最终余额一致。 

最终的解决方案是对 valid (a, b, c) 进行双重求和，其中 a + b + c = n，c 是 VIP 数量，最终余额为 a - b，而有效的 A/B 前缀则使用从反射原理导出的组合系数进行计数。

 ## 算法演练

 我们用两个有意义的量重新解释这个过程：50元顾客的数量和100元顾客的数量。 VIP客户仅充当增加排列多重性的分隔符，但不影响有效性约束。 

### 1. 修复 A、B 和 C 的计数

 我们迭代a（50元客户数量）、b（100元客户数量）和c = n − a − b（VIP客户）的可能值。 对于每个这样的三元组，最终余额为 a − b。 这必须位于 [l, r] 中，否则配置贡献为零。 

这样做的原因是排序约束仅取决于 A 和 B 的相对前缀计数，而 C 是惰性的。 

### 2. 计算具有前缀约束的有效 A/B 序列

 对于固定的 a 和 b，我们对 a A 和 b B 的序列进行计数，使得在每个前缀中，A 计数至少是 B 计数。 这是标准选票号码：$$\text{valid}(a,b) = \frac{a-b+1}{a+1} \binom{a+b}{a}
\quad \text{for } a \ge b$$如果 a < b，则该值为零，因为可行性立即失败。 

该公式来自反映穿过对角线的无效路径。 

### 3.插入VIP客户

 一旦 A/B 骨架固定，我们将 c 个相同的中性元素插入到 n 个位置。 这相当于为 C 选择位置：$$\binom{n}{c}$$### 4. 合并贡献

 对于每个有效的三元组，乘以：

 有效（A/B结构）×VIP放置方式

 并累加模 p。 

### 为什么它有效

 核心不变量是可行性约束仅取决于A和B的前缀，并且不受插入中性元素的影响。 C 的任何排列都会保留 A 和 B 的相对顺序，因此每个有效的交织都唯一对应于有效的骨架加上插入位置的选择。 这种双射确保不会多算或少算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def modinv(a, mod):
    return pow(a, mod - 2, mod)

def solve():
    n, mod, l, r = map(int, input().split())

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % mod

    invfact = [1] * (n + 1)
    invfact[n] = modinv(fact[n], mod)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % mod

    def C(n, k):
        if k < 0 or k > n:
            return 0
        return fact[n] * invfact[k] % mod * invfact[n - k] % mod

    ans = 0

    for a in range(n + 1):
        for b in range(a + 1):
            c = n - a - b
            if c < 0:
                continue

            balance = a - b
            if balance < l or balance > r:
                continue

            # ballot number: valid A/B sequences
            if a == 0:
                ways_ab = 1 if b == 0 else 0
            else:
                ways_ab = (a - b + 1) * C(a + b, a) % mod * modinv(a + 1, mod) % mod

            ways_c = C(n, c)
            ans = (ans + ways_ab * ways_c) % mod

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先预先计算阶乘和逆阶乘，以支持模运算下的二项式系数。 功能`C`计算 O(1) 中的组合。 

然后我们枚举 A 和 B 的所有可行计数。对于每一对，我们计算剩余的 VIP 数量。 平衡检查尽早修剪无效状态，这是至关重要的，因为否则双循环将进行不必要的模幂工作。 

投票公式直接使用 (a + 1) 的模逆来实现。 特殊情况 a = 0 可以避免除法问题并确保在不存在 50 元纸币时的正确性。 

最后，我们乘以所有位置中VIP客户的放置方式数量，并将结果累加。 

一个常见的陷阱是忘记投票公式已经强制执行前缀有效性，因此不需要额外的模拟。

 ## 边缘情况

 一种极端情况是没有百元顾客。 在这种情况下，选票约束消失，并且 A 和 C 的每个排序都是有效的。 该算法可以处理这个问题，因为当 b = 0 时，选票公式会减少到 1，而剩余计数则变成纯粹的组合放置。 

当 b > a 时，会出现另一种边缘情况。 投票公式自动返回零，这正确地排除了无效状态，在这些状态下，某些前缀的改变是不够的。 

第三种微妙的情况是所有客户都是 VIP。 那么 a = b = 0 且 c = n。 该算法只计算一个结构，因为只有一个空的 A/B 序列，并且一旦 C 被视为相同，所有排列都会崩溃为单个配置。
