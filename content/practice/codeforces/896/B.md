 ## 解决方案

 ## 问题理解

 我们正在维护一排`n`位置，每个位置最初都是空的。 随着时间的推移，我们会收到一系列`m`数字。 每个数字到达后，我们必须立即将其分配给其中一个`n`位置，可能会覆盖之前的位置。 目标是确保在此过程中的某个时刻，所有`n`位置被填充，并且结果数组从左到右不递减。 

这不是一次性的建设问题。 我们正在在线构建数组，附加的约束是一旦出现有效的完全填充的排序配置，该过程就会停止。 在那一刻之后，进一步的决定不再重要，因为交互立即结束。 

约束结构是关键：`n`和`m`可能很大（典型的 CF 交互边界），因此任何在每个步骤后重新计算全局结构的策略都太慢。 反复检查所有的解决方案`n`每次移动的位置会像`O(nm)`当两者都很大时就无法生存。 

一个微妙的失败案例来自于没有结构的贪婪放置。 例如，如果我们总是将每个数字放在最左边的可能位置或任意覆盖，我们可以轻松地创建存在有效顺序但我们破坏了它的情况。 由于允许覆盖，较早的不良放置可能会使数组暂时排序但很脆弱，从而在下次更新时中断。 

另一个危险是过早终止逻辑。 在交互问题中，成功后继续阅读会产生未定义的行为。 例如，如果`n = 2`我们已经达到了`[1, 3]`在第 3 轮之后，读取第 4 轮输入会破坏协议，即使逻辑上无害。 

## 方法

 蛮力思维是在每一步模拟所有可能的选择。 收到一个值后，我们尝试将其放入每个`n`位置并递归地探索未来的序列是否可以导致排序的完整数组。 这很快就会呈指数增长：每个`m`步骤分支为`n`选择、给予`O(n^m)`州。 即使基于部分排序的修剪仍然留下了棘手的搜索空间。 

我们需要一种压缩状态的方法。 关键的观察是，我们始终不关心确切的排列，只关心达到最终的排序完成。 这表明我们应该维护一个结构，保留将部分解决方案扩展到非递减完整数组的能力。 

关键的见解是始终以保持“最佳可能前缀”结构的方式维护数组。 我们不考虑任意放置，而是将数组视为一个系统，其中每个位置都有一个当前值，并且我们希望保持灵活性：小值应保留在左侧，大值应向右漂移。 这正是总是修复局部违规的贪婪放置策略所强制执行的行为。 

在交互式建设性问题中实现此目的的标准方法是维护数组，并在每次插入后通过向外推送违规来本地修复顺序。 由于值每步仅在一个位置发生变化，因此每次移动引入的混乱是有限的，并且可以确定性地纠正。 

最优解决方案将每个操作减少为选择一个以最小干扰保留或恢复排序结构的位置，而不是全局搜索。

 ## 算法演练

 我们维护一个数组`a[1..n]`，最初为空。 

1. 将所有位置初始化为空，概念上视为非常大的哨兵值或表示“未设置”的特殊标记。 这使我们能够在每次检查时无需特殊的情况下进行比较。 
2. 对于每个传入的值`x`，扫描放置的位置`x`对订购造成的干扰最小。 自然目标是最左边的位置，其中插槽为空或`a[i] <= x`同时保留潜在的非递减结构。 
3. 如果多个位置有效，则优先选择不违反维持排序顺序的可能性的最早位置。 此首选项将较小的值尽可能保留在左侧，从而为较大的值保留未来的灵活性。 
4. 地点`x`进入所选位置，覆盖任何先前的值。 
5.插入后，进行局部修正：如果`a[i] > a[i+1]`对于受更新、交换或重新定位值影响的任何相邻对，以便尽可能恢复非递减属性，而不改变其他地方已经一致的结构。 
6. 每轮结束后，检查所有位置是否已满且数组是否非递减。 如果是，则输出当前位置并立即终止。 

### 为什么它有效

 中心不变量是，在每次操作之后，在所见值的所有可能放置中，该算法保留至少一个有效的部分配置，该配置可以扩展到完整的非递减数组。 贪婪选择永远不会消除所有有效的完成，因为它只解决通过插入单个新值而产生的局部冲突，并且它始终以保留排序可行性的方式放置值，即保持较小的值尽可能靠左，较大的值尽可能靠右。 由于最终条件纯粹是全局排序，因此在每个步骤之后保持局部一致性足以保证一旦出现完全填充状态，它一定已经排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m, c = map(int, input().split())
a = [None] * n
filled = 0

for _ in range(m):
    x = int(input())

    pos = -1

    for i in range(n):
        if a[i] is None:
            pos = i
            break
        if a[i] <= x:
            pos = i

    if pos == -1:
        pos = n - 1

    if a[pos] is None:
        filled += 1
    a[pos] = x

    i = pos
    if i > 0 and a[i - 1] is not None and a[i] is not None and a[i - 1] > a[i]:
        a[i - 1], a[i] = a[i], a[i - 1]
        i -= 1

    i = pos
    if i + 1 < n and a[i] is not None and a[i + 1] is not None and a[i] > a[i + 1]:
        a[i], a[i + 1] = a[i + 1], a[i]

    if filled == n:
        ok = True
        for i in range(n - 1):
            if a[i] > a[i + 1]:
                ok = False
                break
        if ok:
            print(pos + 1)
            sys.stdout.flush()
            break

    print(pos + 1)
    sys.stdout.flush()
```该实现保留一个显式数组并在线更新它。 位置选择逻辑是贪婪扫描，尝试将当前值放置在现有值中最右边的兼容位置，或者如果可能的话，放置在第一个空槽中。 这确保较小的值倾向于保留在左侧，这是最终排序的结构要求。 

放置后，仅尝试局部相邻校正，因为单次覆盖只能创建相邻反转。 与完全重新排序相比，这使得更新成本较低。 

填充所有槽后立即执行终止检查，确保我们在满足条件后立即正确停止交互。

 ## 边缘情况

 一个关键的边缘情况是值按严格降序到达。 在这种情况下，最左边的朴素放置会不断覆盖有用的结构并阻止收敛。 贪婪的最右兼容放置确保较小的值提前向左推送，因此最终配置仍然可以排序。 

另一种边缘情况是重复相同的值。 由于相等值的任何排列都是有效的，因此算法不需要仔细区分位置，并且自动保持稳定性，因为比较将相等视为安全放置。 

最后一个边缘情况是提前完成。 当数组第一次完全填充并排序时，算法必须立即停止。 即使内部状态已经正确，继续读取进一步的输入也会破坏交互协议。
