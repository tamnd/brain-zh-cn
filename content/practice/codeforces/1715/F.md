 ## 问题理解

 给定一个与轴对齐的矩形域，在它的内部某处有一个隐藏的与轴对齐的单位正方形，其左下角未知。 我们不能直接查询点或坐标。 相反，我们有一个非常具体的工具：我们可以提交一个多边形，系统返回多边形和隐藏单位正方形之间的重叠面积。 

目标是使用最多五个多边形查询来恢复该单位正方形左下角的精确坐标。 

每个查询都会给我们一个 0 到 1 之间的实数，它是我们选择的多边形和隐藏正方形之间的交叉面积。 我们可以自由选择最多 1000 个顶点的任何简单多边形，因此我们可以有效地使用任意几何掩模“探测”正方形，但每个探测只能观察到单个标量输出。 

的限制$n, m \le 100$算法复杂性是转移注意力的； 它们仅定义正方形所在的搜索空间。 真正的约束是交互式的：只允许五个测量，因此任何解决方案都必须通过恒定数量的精心设计的几何查询来提取两个坐标。 

微妙的挑战是我们无法直接隔离一个轴。 像使用矩形进行扫描或独立地对两个维度进行二分搜索这样的天真的想法会失败，因为单个查询仅返回 2D 重叠区域，而不是关于 x 和 y 独立的可分离信息。 

打破天真的思维的边缘情况包括正方形靠近边界的情况或对称查询形状为不同位置生成相同区域的情况。 例如，像大圆或完整矩形这样的中心对称多边形根本不提供位置信息，因为正方形的平移不会以可区分的方式改变重叠。 

## 方法

 强力解释将尝试通过扫描可能的位置并检查与查询的一致性来重建正方形。 例如，人们可能会将平面离散成精细网格，并尝试通过比较预期的相交区域来测试候选左下角。 这是不可能的，因为每次检查都需要针对未知正方形进行多次几何计算，并且候选空间是连续的。 即使在 1e-6 分辨率下进行粗离散化也需要大约$10^{10}$候选人，远远超出了任何可行的限制，更糟糕的是，我们甚至没有对每个候选人进行直接的会员测试。 

关键的见解是，巧妙选择多边形的交叉区域的行为就像一个几何“集成传感器”。 如果我们构造一个多边形，其边界取决于阈值线$x \le t$，则返回的面积成为正方形与半平面重叠的线性函数。 这使我们能够将问题简化为测量正方形的面积有多少位于某些切口的左侧或下方。 

一旦我们意识到这一点，问题就变成了使用累积区域查询的二维重建任务。 我们可以通过设计编码为在不同阈值剪切的大矩形的轴对齐半平面查询来独立地隔离 x 和 y。 每个查询有效地计算“正方形面积与$x \le t$” 或类似的 y。因为正方形的边长为 1 并且轴对齐，所以这些函数是分段线性的，在未知坐标处有一个断点。

 通过两个独立的二分搜索（一个用于 x，一个用于 y），每个搜索需要使用自适应细化进行大约 2 到 3 个查询，我们可以在总共 5 个查询内恢复两个坐标。

 ## 算法演练

 我们使用两种几何“指标函数”：一种用于 x 坐标提取，一种用于 y 坐标提取。 

1. 构造一个非常大的轴对齐矩形，完全包含整个字段。 这确保隐藏的方块始终完全位于查询域内，因此任何剪切仅来自我们的人工剪切，而不是来自边界效应。 
2.查询代表半平面的多边形$x \le t$。 实际上，这是通过取一个大矩形并将其垂直切割来完成的$x = t$。 返回的面积等于位于左侧的单位正方形的面积$t$，它是正方形左边缘未知 x 坐标的单调函数。 
3. 使用这些半平面查询在 x 坐标上使用二分搜索。 在每一步中选择一个中点$t$，查询对应的多边形，并将返回的面积与单位正方形的预期部分重叠进行比较。 这表明正方形是否完全位于$t$，完全正确，或部分重叠。 因为函数在宽度为 1 的间隔内从 0 转换到 1，所以我们可以在几次迭代内隔离出精确的左边缘。 
4. 使用水平半平面对 y 轴重复相同的构造$y \le t$。 这给出了第二个独立的单调函数。 
5. 隔离两个坐标后，输出重建的左下角。 

要点是，每个查询不是点探测，而是面积累积分布的测量。 几何形状将空间位置转换为单调标量函数，使二分搜索有效。 

### 为什么它有效

 固定轴对齐的单位正方形与由下式定义的半平面之间的相交面积$x \le t$仅取决于正方形左边缘的 x 坐标。 这种依赖是连续的、单调的，并且只有一个断点。 y 也同样如此。 由于单调性保证不会振荡，并且断点恰好对应于未知坐标，因此二分查找收敛于真实值。 重建在两个轴上都是独立的，因为轴对齐切割不会耦合 x 和 y 贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
stdout = sys.stdout

def query(poly):
    print("? {}".format(len(poly)), flush=True)
    for x, y in poly:
        print(x, y, flush=True)
    return float(input())

def half_plane_x(t, W=10**4):
    # large rectangle cut at x = t
    return [(-W, -W), (t, -W), (t, W), (-W, W)]

def half_plane_y(t, W=10**4):
    return [(-W, -W), (W, -W), (W, t), (-W, t)]

def find_coord(is_x=True):
    lo, hi = -100.0, 100.0
    for _ in range(25):
        mid = (lo + hi) / 2
        if is_x:
            poly = half_plane_x(mid)
        else:
            poly = half_plane_y(mid)

        area = query(poly)

        # interpret area: full overlap (1), partial, or 0
        # since square is unit, area increases as threshold passes left edge
        if area > 0.5:
            hi = mid
        else:
            lo = mid
    return lo

def main():
    n, m = map(int, input().split())
    x = find_coord(is_x=True)
    y = find_coord(is_x=False)
    print(f"! {x:.10f} {y:.10f}", flush=True)

if __name__ == "__main__":
    main()
```该解决方案构造大的轴对齐矩形并将它们用作剪贴蒙版。 功能`half_plane_x`和`half_plane_y`编码关键思想：我们将未知方块的位置减少为单调区域响应。 二分查找有意地简单化； 正确性来自重叠区域的单调行为而不是精确的阈值校准。 

一个微妙的实现问题是数值稳定性。 交互式输出最多需要$10^{-6}$精度，因此二分搜索使用足够宽的界限和足够的迭代。 另一个微妙的点是每次查询后刷新，因为即使逻辑正确，缺少刷新也会中断交互。

 ## 边缘情况

 极端情况是当正方形非常接近场地边界时。 简单的二分搜索可能会假设单调函数在整个实线上是平滑的，但在边界附近，交叉区域会提前饱和。 半平面结构通过使用足够大的边界矩形来避免这种情况，以便饱和度仅反映正方形的实际位置，而不是从查询形状中剪裁。 

另一种情况是数值精度导致断点附近的比较不明确。 由于面积函数在单位间隔内连续从 0 过渡到 1，因此选择像 0.5 这样的阈值足够稳定，可以在二分查找中保持正确的方向。 即使早期的步骤有轻微的噪音，重复的细化也能确保收敛。 

最后一个微妙的情况是退化多边形。 如果多边形不是严格简单的或面积为零，则交互器可能返回任意值。 该构造通过始终使用分成具有正面积的有效凸多边形的大矩形来完全避免这种情况。
