 ## 解决方案
 ## 问题理解

 我们被要求构造一个长度的数组`n`由非负整数组成。 必须同时满足两个全局约束。 

首先，所有元素的总和必须精确`s`。 其次，如果每个元素除以`k`并取底，这些商的总和必须恰好是`b`。 第二个条件可以解释为计算有多少个完整的大小块`k`存在于整个数组中。 

每个元素独立贡献：一个值`x`贡献`x // k`为美丽做出贡献`x`至总和。 任务是分配总金额`s`穿过`n`同时保证满槽总数`k`- 块等于`b`。 

限制条件很大：`n`测试中高达 1e5，`k`最多 1e9，并且`s`最多 1e18。 这立即排除了尝试所有分布或在每个位置的可能值上使用嵌套循环构建候选的任何方法。 每个测试用例的线性构造是唯一可行的方向。 

当在施工之前就不可能实现可行性时，就会出现微妙的边缘情况。 例如，如果`k = 6`,`b = 3`， 和`s = 12`和`n = 3`，那么达到美感的最小可能总和`3`已经太大或太结构化而无法匹配`s`。 这是因为每个单位的美至少需要`k`数组中某处的总贡献，所以`s`必须足够大以支持`b`完整的块。 

另一种故障模式发生在`b`太大而无法分布`n`元素。 如果`b > s // k`，那么即使将所有质量集中到一个元素中也无法创建足够的完整划分。 

真正的困难不是计算可行性，而是在不打破任何一个约束的情况下分配“区块贡献”和剩余价值。 

## 方法

 一个蛮力的想法是将每个元素视为一个变量并尝试增量分配值。 对于每个位置，我们可以尝试以下值`0`到`s`，计算当前总和和美度，然后回溯。 这在原则上是正确的，但完全不可行。 即使是为了`n = 100`，状态空间爆炸，并且对于`n = 10^5`，这是不可能的。 

关键的观察结果是，美丽的贡献是由大小块组成的`k`。 任意数量`x`可以分解为：`x = (x // k) * k + (x % k)`这将每个元素分为“块部分”和“剩余部分”。 美观仅取决于块部分，而其余部分则完全不影响美观。 

所以问题就变成了：我们需要准确分配`b`大小块`k`整个数组，并将剩余的总和作为余数自由分配，同时保持总和等于`s`。 

如果我们首先分配尽可能多的完整结构，就会出现一个干净的结构`k`将尽可能多的块放入一个元素中，然后将剩余的块分配为`k`其他位置的增量。 修复美观后，我们将剩余的金额分配到任何元素中，而不影响楼层划分结构。 

我们只需要保证美容所需的最低总金额即可`b`是`b * k`，以及剩余的松弛`s - b * k`可以任意分配。 

如果`s < b * k`，无解。 否则，我们构造一个基本数组`b`的单位`k`，然后分配剩余的金额。 

最后，我们确保没有元素由于溢出而意外获得额外的块`k`，通过在每个位置最多放置一个大值来小心地放置。

 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们贪婪地构建数组，同时控制有多少个已满`k`-阻止每个元素的贡献。 

1. 通过验证是否可行来检查可行性`b * k ≤ s`。 如果不是，则没有阵列可以在不超过总和的情况下产生足够的完整块。 这是因为每个单位的美容成本至少`k`在价值上。 
2.初始化一个size的数组`n`全为零。 我们先分配需要的美女`b`集中进入第一个元素。 这可以避免过早地分配块并简化跟踪。 
3. 设置`a[0] = b * k`。 这保证了该元素所贡献的美感正是`b`， 自从`(b * k) // k = b`。 目前还没有其他元素有助于美丽。 
4. 从剩余金额中减去该捐款：`remaining = s - b * k`。 
5. 现在我们分发`remaining`跨阵不改美。 由于任意值`< k`对美的贡献为零，我们可以放心地将价值放在`[0, k-1]`在任何职位上。 
6. 从左到右填充元素，总计为`k-1`每个元素直到`remaining`已经筋疲力尽了。 这确保没有新的`k`-block 是意外创建的。 
7. 输出结果数组。 

### 为什么它有效

 该结构将所有美观贡献隔离到单个受控元素中。 由于仅`a[0]`允许≥`k`，它单独决定了总楼层数。 所有其他元素都严格保留在下面`k`，保证对美丽零贡献。 剩余金额的分配不会超过会创建额外区块的阈值。 这独立地保留了两个约束，使构造安全且具有确定性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, b, s = map(int, input().split())

        min_sum = b * k
        if min_sum > s:
            print(-1)
            continue

        res = [0] * n

        # allocate all beauty into first element
        res[0] = b * k
        remaining = s - b * k

        # distribute remaining without creating new k-blocks
        for i in range(n):
            if remaining == 0:
                break
            add = min(k - 1, remaining)
            res[i] += add
            remaining -= add

        if remaining > 0:
            print(-1)
        else:
            print(*res)

if __name__ == "__main__":
    solve()
```解决方案首先检查所需的完整数量`k`考虑到总金额，捐款甚至是可能的。 如果不是，则立即驳回该案件。 

构建步骤使用精确倍数将所有所需的美感放入第一个元素中`k`。 这确保了楼层划分总和恰好是`b`并且不依赖于剩余值的分配方式。 

分配的循环`remaining`被仔细限制为`k - 1`，这阻止了任何新元素对美的贡献。 这是核心实施细节：跨越门槛`k`会默默地增加美感，打破正确性。

 ## 边缘情况

 一个关键的边缘情况是`b * k == s`。 在这种情况下，就没有剩余的余地了。 该算法分配`a[0] = s`并将所有其他元素保留为零。 由于所有其他值均低于`k`，它们没有贡献任何东西，并且第一个元素单独产生精确的`b`美丽。 该建筑仍然有效。 

另一个边缘情况是当`k = 1`。 在这里，每一个整数都充分体现了美感。 条件变为`sum(a) = s`和美丽等于`s`。 这迫使`b = s`。 如果不是，则不存在解决方案。 该算法自然地处理这个问题，因为`b * k = b`必须等于`s`。 

最后一个边缘情况是`n = 1`。 唯一可能的数组是单个值`s`。 条件简化为检查是否`s // k == b`，它与结构匹配，因为我们将唯一的元素设置为`b * k`并要求`s = b * k`。
