 ## 解决方案
 ## 问题理解

 我们得到了一系列预定的行程，每个行程都有开始时间和结束时间。 Chad 按给定顺序执行这些行程。 关键机制是，如果在他仍在忙于完成先前延迟的行程时开始行程，则行程不会按原定时间开始。 相反，它会向前推进，并在他获得自由时开始。 

由于这种连锁效应，迟到的长途旅行可能会将延迟传播到所有后续旅行，即使这些后续旅行最初不会重叠。 

乍得在出发前最多可以取消 K 趟行程。 其余行程按其原始相对顺序进行处理，并适用相同的延迟规则。 

目标是选择删除最多 K 个行程，以便在使用延迟传播规则处理剩余调度后，最终完成时间尽可能短。 

输出是单个值：完成所有剩余行程的最早可能时间。 

约束 N ≤ 4000 强烈表明 O(N²) 或 O(N²K) 动态规划解决方案是可以接受的。 考虑所有子集或直接模拟所有取消的三次或更差方法是不可行的，因为子集的数量呈指数增长。 K 作为小删除预算的存在通常表明 DP 超过了前缀和删除。 

当应用贪婪直觉时，会出现微妙的失败案例。 例如，总是删除导致最大立即延迟的行程可能会失败，因为删除较小的早期重叠可以防止稍后代价更高的级联。 当假设可以在每个间隔独立地决定取消时，会出现另一个失败，因为延迟传播耦合了所有未来的决定。 

一个具体的问题模式是：

 输入：```
3 1
1 10
2 3
3 4
```如果我们删除第一个间隔，因为它很大，我们就会提前完成。 但如果我们删除其中一个小间隔，重叠的结构就会发生不同的变化。 正确的解决方案取决于全局交互，而不是局部间隔成本。 

## 方法

 一种强力方法是尝试至少 N-K 个行程的所有子集，模拟每个子集的时间表，并计算最终的完成时间。 对于每个子集，我们将对剩余行程进行排序或迭代，并在线性时间内应用传播规则。 这会导致大约 O(2^N · N) 的行为，即使对于 N = 40 也是完全不可行的，更不用说 4000 了。 

关键的观察结果是该过程基本上是连续的。 一旦我们确定了行程的子集，最终的时间表就是确定性的：我们只需模拟前进并累积完成时间。 这表明对排序序列的前缀和所使用的删除数进行动态编程。 

我们将问题重新解释为：我们按顺序处理行程，并且在每一步中我们决定要么保留行程（并在需要时延长当前时间），要么删除它（消耗 K 个删除之一）。 困难在于，保留行程不仅仅增加其持续时间，它还通过 max(current_time, s_i) + (e_i - s_i) 与当前时间交互。 这种依赖性使得朴素的 DP 不够充分，除非我们仔细构建状态转换。 

当我们在索引和删除上定义 DP 时，就会出现正确的结构，同时通过始终模拟转换来隐式推进当前完成时间。 由于 N 足够小，我们可以将 DP 状态视为“处理前 i 个行程并删除其中 j 个行程后的最佳可能完成时间”，但我们还必须通过仅传播来自先前状态的可行时间转换来确保正确性。 

这导致了分层 DP，其中每个状态通过跳过或采取行程来扩展到下一个索引，并直接模拟时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集 | O(2^N·N) | O(2^N·N) | O(N) | 太慢了|
 | DP 前缀和删除 | O(N²K) 或 O(NK) 优化 | O(NK) | 已接受 |

 ## 算法演练

 我们维护一个 DP 表，其中 dp[i][j] 表示考虑前 i 个行程并取消其中 j 个行程后的最早可能完成时间。 

1. 初始化 dp[0][0] = 0，因为在任何行程之前我们已在时间 0 完成。所有其他状态都设置为无穷大，因为它们尚不可到达。 
2. 按从 1 到 N 的顺序迭代行程。对于每个行程 (s_i, e_i)，我们将其持续时间计算为 d_i = e_i - s_i。 这种分离使我们能够干净地应用延迟规则。 
3. 对于每个 dp[i-1][j]，我们考虑两个转换。 
4. 第一个转换是取消。 如果我们取消行程 i，我们会从 dp[i-1][j] 移动到 dp[i][j+1]，而不改变当前时间。 该模型完全跳过行程，消耗一次取消。 
5. 第二个转变是保持行程。 如果我们保留它，实际的开始时间将变为 max(dp[i-1][j], s_i)，因为我们要么在预定的开始之后到达，要么等到它开始。 完成时间变为 max(dp[i-1][j], s_i) + d_i，我们相应地更新 dp[i][j]。 
6. 处理完所有转换后，答案是所有 j ≤ K 中的最小 dp[N][j]，因为我们最多可以使用 K 个取消。 

重要的是 dp 存储实际时间值，因此延迟传播在转换中隐式编码，而不是单独模拟。 

### 为什么它有效

在每一步 i，dp[i][j] 使用前 i 个行程中的 j 个取消来捕获可实现的最佳完成时间。 前 i 个行程的任何有效时间表都可以通过为每个行程决定是否删除或处理来构建。 保持行程的转换与延迟传播下的现实世界时间演变完全匹配，因为任何时刻的系统状态都由当前完成时间完全描述。 不需要额外的历史记录。 因此，所有有效的调度都在 DP 中表示，并且最终状态的最小值是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, K = map(int, input().split())
    trips = [tuple(map(int, input().split())) for _ in range(N)]
    
    INF = 10**30
    dp = [[INF] * (K + 1) for _ in range(N + 1)]
    dp[0][0] = 0

    for i in range(1, N + 1):
        s, e = trips[i - 1]
        d = e - s

        for j in range(K + 1):
            if dp[i - 1][j] == INF:
                continue

            cur = dp[i - 1][j]

            # skip
            if j + 1 <= K:
                dp[i][j + 1] = min(dp[i][j + 1], cur)

            # take
            start = cur if cur > s else s
            finish = start + d
            dp[i][j] = min(dp[i][j], finish)

    print(min(dp[N]))

if __name__ == "__main__":
    solve()
```DP表是逐行构建的，其中每一行对应于已处理的行程前缀。 跳过过渡会增加删除计数而不影响时间。 镜头转换显式地模拟等待行程开始（如有必要），然后添加其持续时间。 

一个常见的陷阱是忘记开始时间取决于当前的累积时间。 直接使用 e_i 而不是计算持续时间会破坏正确性，因为延迟会改变整个时间表。 

另一个微妙之处是允许“最多 K”删除，这是通过取所有 dp[N][j] 的最小值而不是强制 j = K 来处理的。

 ## 边缘情况

 一种极端情况是所有行程严重重叠。 例如：```
3 1
1 10
2 11
3 12
```如果我们在没有取消的情况下进行模拟，由于完全传播，最终时间变为 12。 DP 正确评估了跳过每个可能的间隔，并发现删除第一次行程会产生一个小得多的链，因为它阻止了最初的大锚点推动一切向前。 

另一种边缘情况是当 K = 0 时。在这种情况下，DP 退化为每次行程都会发生的单个模拟路径。 该算法自然会处理这个问题，因为所有跳过转换都被禁用。 

最后的边缘情况是当取消量大到足以移除所有长锚点时。 DP 正确地探索组合，因为每个前缀状态都独立地考虑采用和跳过，确保在不需要显式子集枚举的情况下出现大小为 N-K 的最佳子集。
