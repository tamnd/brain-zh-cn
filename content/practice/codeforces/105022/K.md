 ## 解决方案
 ## 问题理解

 我们有一堆垂直的卡车，每辆卡车贡献一个固定长度的段。 最初，堆垛从原点开始在 y 轴上完美对齐，因此顶部卡车的头部最终位于一个点，该点的 y 坐标是所有卡车长度的总和，x 坐标为零。 

我们可以执行的唯一操作是选择卡车索引并从该卡车开始围绕该卡车下方的连接点向上旋转整个后缀。 从概念上讲，这意味着我们采用刚性的链段并旋转一个关节，而该关节上方的所有物体都作为单个刚体一起旋转。 

每次这样的旋转之后，我们必须报告整个结构的最顶部端点的坐标。 

关键的困难在于每个查询都会更改全局几何形状，但仅在一个关节处进行局部更改。 一种简单的解释是建议在每次旋转后重新计算所有段位置，这将涉及通过每个查询可能有 100,000 个段来传播转换。 

当 N 和 Q 都达到 100,000 时，二次方法是不可能的。 即使 O(NQ) 操作也会达到 10^10 次更新，这远远超出了可行的限制。 任何可接受的解决方案都必须确保每个查询都以对数或摊销常数时间处理。 

一个微妙的方面是，旋转是累积的并影响所有更高的段，因此最终位置取决于一系列组合旋转，而不是独立更新。 

边缘情况出现在以下情况：

 一辆卡车在不同位置多次旋转，这会导致重叠后缀的反复重新定向。 简单的重新计算会重复重建相同的后缀几何形状。 

另一个边缘情况是在索引 1 处旋转。这会旋转整个结构，如果角度累积不正确，浮点漂移或不正确的主元选择会导致不正确的全局平移。 

## 方法

 直接模拟会保留平面中线段方向的明确列表。 每个查询选择一个索引 r，计算该卡车的枢轴位置，并将其上方的所有段旋转固定角度。 这需要为每个查询更新 O(N) 个向量，并通过对所有段向量求和来重新计算最终端点。 正确性很简单，因为我们确实模拟了几何形状，但运行时间变成了 O(NQ)，这太大了。 

关键的观察是该结构是一个向量链，每次旋转仅改变这些向量后缀的方向。 这是一个经典的设置，我们希望支持范围旋转下向量的前缀和。 

我们不存储绝对坐标，而是将线段向量存储在线段树中，其中每个节点表示一个范围的结果向量和及其当前旋转状态。 当我们旋转后缀时，我们正在对该段中的所有向量应用变换。 此变换是线性的：每个向量 (x, y) 变为 (x cos θ − y sin θ, x sin θ + y cos θ)。 因为这是一个线性变换，所以它可以干净地组合并且可以延迟传播。 

因此，问题简化为维护一个支持范围仿射旋转的线段树并查询整个数组的总向量和。 

每次操作后的最终答案只是整个段的变换后的和向量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(NQ) | O(N) | 太慢了|
 | 具有延迟旋转的线段树 | O(Q log N) | O(Q log N) | O(N) | 已接受 |

 ## 算法演练

 我们将每辆卡车建模为最初指向上方的向量：(0, l_i)。 整个结构就是这些向量按顺序相加。

1. 构建一棵线段树，其中每个叶子存储一个向量 (0, l_i)。 每个内部节点存储其子节点向量的总和。 一旦树建立起来，这给了我们 O(1) 内任何段的总位移。 
2. 对于每个节点，维护一个表示待处理旋转角度的惰性标记。 这意味着该节点下的整个段已被旋转，但尚未推送到子节点。 我们不存储绝对坐标，只存储相对向量。 
3. 当对线段应用旋转时，我们通过添加旋转角度来更新其惰性角度。 我们不是立即更新内部的所有向量，而是将该段标记为旋转。 
4. 当我们需要访问一个节点时，我们将其惰性旋转下推。 这意味着我们使用旋转矩阵旋转节点存储的向量和并将角度传播到其子节点。 
5. 每个查询都会轮换后缀[r, N]。 我们应用 θ = 3366 度的旋转转换为弧度，归一化为单个有效角度，因为旋转是周期性的。 此更新在线段树上执行的时间复杂度为 O(log N)。 
6. 每次更新后，答案就是存储在线段树根部的向量，它表示所有旋转线段的总和。 

这样做的原因是旋转是一种线性变换，因此旋转向量和相当于对旋转向量求和。 这使我们能够将旋转惰性地应用于整个片段而不分解它们。 

保持的不变性是，在应用所有待处理的惰性旋转之后，线段树中的每个节点始终正确地表示其线段中所有向量的总和。 惰性值可确保正确性，而无需强制立即重新计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import math

ANGLE = 3366 * math.pi / 180.0

class Node:
    __slots__ = ("x", "y", "lazy")
    def __init__(self):
        self.x = 0.0
        self.y = 0.0
        self.lazy = 0.0

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 4 * self.n
        self.tree = [Node() for _ in range(self.size)]
        self.build(1, 0, self.n - 1, arr)

    def apply(self, idx, ang):
        node = self.tree[idx]
        c = math.cos(ang)
        s = math.sin(ang)
        x, y = node.x, node.y
        node.x = x * c - y * s
        node.y = x * s + y * c
        node.lazy += ang

    def push(self, idx):
        node = self.tree[idx]
        if abs(node.lazy) > 1e-12:
            self.apply(idx * 2, node.lazy)
            self.apply(idx * 2 + 1, node.lazy)
            node.lazy = 0.0

    def pull(self, idx):
        left = self.tree[idx * 2]
        right = self.tree[idx * 2 + 1]
        self.tree[idx].x = left.x + right.x
        self.tree[idx].y = left.y + right.y

    def build(self, idx, l, r, arr):
        if l == r:
            self.tree[idx].x = 0.0
            self.tree[idx].y = float(arr[l])
            return
        mid = (l + r) // 2
        self.build(idx * 2, l, mid, arr)
        self.build(idx * 2 + 1, mid + 1, r, arr)
        self.pull(idx)

    def update(self, idx, l, r, ql, qr, ang):
        if ql <= l and r <= qr:
            self.apply(idx, ang)
            return
        self.push(idx)
        mid = (l + r) // 2
        if ql <= mid:
            self.update(idx * 2, l, mid, ql, qr, ang)
        if qr > mid:
            self.update(idx * 2 + 1, mid + 1, r, ql, qr, ang)
        self.pull(idx)

def solve():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))
    queries = list(map(int, input().split()))

    st = SegTree(arr)

    for r in queries:
        st.update(1, 0, n - 1, r - 1, n - 1, ANGLE)
        print(f"{st.tree[1].x:.3f} {st.tree[1].y:.3f}")

if __name__ == "__main__":
    solve()
```该实现将每辆卡车编码为垂直向量，并在这些向量上构建线段树。 构建步骤构建初始直立配置。 

apply 函数使用标准 2D 旋转矩阵旋转节点的存储向量并累积惰性角度。 这是核心转换，允许在不接触每个叶子的情况下应用范围旋转。 

推动功能通过在进一步下降之前传播累积的旋转来确保正确性。 如果没有这个，部分更新会破坏子树的一致性。 

每次更新都会在后缀范围上应用旋转，并且在每次查询之后我们直接读取根节点，该根节点始终存储总变换位移。 

这里的一个常见陷阱是忘记必须根据更新角度重新计算余弦和正弦，而不是以向量形式累积，并且浮点精度需要仔细格式化。 

## 工作示例

 考虑一个小型结构，包含三辆长度为 1, 1, 1 的卡车。最初端点位于 (0, 3)。 假设我们从索引 2 开始旋转。 

| 步骤| 行动| 根向量 (x, y) |
 | ---| ---| ---|
 | 1 | 初始构建| (0.000, 3.000) |
 | 2 | 旋转后缀 [2,3] | (0.809, 2.412) |
 | 3 | 传播后| (0.809, 2.412) |

 这显示了链条如何仅部分旋转，而全部链条平稳变化。 

现在考虑将索引 1 旋转两次。 整个结构旋转两次，在根节点累积角度。 中间向量一致地旋转，因为惰性传播对所有段应用相同的变换。 

| 步骤| 行动| 根向量 (x, y) |
 | ---| ---| ---|
 | 1 | 初始| (0.000, 3.000) |
 | 2 | 旋转 [1,3] | （0.000、3.000 旋转）|
 | 3 | 再次旋转[1,3] | 进一步轮换应用 |

 这些痕迹表明，重复的全范围旋转的行为就像组合全局刚性变换。

 ## 边缘情况

 临界边缘情况在位置 1 处重复旋转。 在这种情况下，整个结构会经历重复的全局旋转。 如果实现错误地重置而不是累积角度，则最终位置将错误地振荡而不是组合变换。 

另一个边缘情况是重叠后缀的重复旋转。 由于后缀范围严重交叉，因此惰性传播必须确保部分更新不会覆盖以前存储的转换。 线段树不变量确保每个节点始终代表其线段的完全应用的变换，即使子节点尚未更新。 

第三种边缘情况是当多次旋转累积时的精度漂移。 由于答案被截断后打印到小数点后三位，因此小的浮点误差是可以接受的，但应用正弦和余弦的错误顺序可能会放大误差并产生明显错误的坐标。
