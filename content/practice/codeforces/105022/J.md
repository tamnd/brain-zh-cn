 ## 解决方案
 ## 问题理解

 我们得到一个仅由数字组成的字符串`1`和`2`，并且我们可以使用有限的硬币预算对其进行修改。 目标是将这个字符串转换为字典顺序中尽可能小的数字，这意味着我们想要尽可能多的数字`1`s 尽可能放在前面，并且在相等的前缀中，我们希望前面的位置尽可能小。 

有两种类型的操作。 我们可以用任意数字覆盖任何位置`1`或数字`2`，根据我们写入的数字支付固定费用。 我们还可以交换任意两个位置，支付等于它们索引距离的成本。 预算`K`限制了所有操作的总成本。 

关键的困难在于交换不是成本固定为1的局部相邻交换，而是成本取决于距离的任意远程交换。 这使得问题感觉像是加权约束排序和选择性重写的组合。 

这些限制迫使我们走向`O(N log N)`或者`O(N)`解决方案。 和`N`高达 200,000 以及`K`直到 10^9，任何二次配对或流动公式都是不可能的。 甚至`O(N^2)`位置的贪婪匹配太大。 

天真的解释会尝试模拟交换来对字符串进行排序，或者尝试对前缀和剩余预算进行动态编程。 两者都失败了，因为国家需要跟踪头寸安排和剩余硬币，这太大了。 

一些微妙的边缘情况揭示了贪婪局部推理失败的原因。 如果字符串已经大部分`1`只有几个`2`s 出现得早，一个幼稚的策略可能会尝试将它们与远方交换`1`s，但长交换的成本可能超过简单地覆盖数字。 相反，如果由于位置附近而导致掉期成本较低，则重写可能会造成浪费。 交换距离成本和覆盖成本之间的权衡是核心张力。 

## 方法

 蛮力的想法是考虑所有操作序列：选择要重写的位置、要交换的对以及以什么顺序。 即使我们忽略排序问题并假设我们首先交换为排列然后重写，我们仍然会在预算下选择交换和替换的子集。 可能性的数量呈指数级增长，因为每对位置都可以交换或不交换，并且每个位置都可以用两种方式重写。 这在非常小的情况下是完全不可行的`N`。 

关键的观察是交换仅改变顺序，而不改变值，并且其成本仅取决于最终配对距离。 如果我们将交换解释为一种排列索引的方式，那么任何排列都可以分解为交换，并且实现排列的最小成本是其类似反转的成本结构。 然而，对于这个问题，我们不需要任意排列。 我们只关心生成一个按字典顺序排列的最小字符串，这意味着我们想要推送`1`尽可能靠左。 

这将问题转化为选择哪些位置将成为`1`在最后的字符串中。 一旦我们决定了最终的位置集`1`，最佳排列是将它们按升序放置在最左边的可能位置。 实现这一目标的成本取决于匹配原始`1`s 并可能转换`2`进入`1`使用覆盖操作，加上移动的成本`1`如果我们选择重新定位它们而不是重写，则可以通过交换来实现。 

一个关键的简化来自于比较两种获得`1`在一个位置：要么我们已经有一个`1`并使用交换将其移动到那里，或者我们将当前数字转换为`1`使用重写成本`c1`。 同样，转动一个`1`变成一个`2`受`c2`。 由于目标在字典顺序上是最小的，所以我们从不想要额外的`2`时间还早，所以主要决定是有多少`1`我们可以以最低的成本将其放在前面。 

这减少了对现有的配对`1`s 与目标前缀位置按顺序排列。 最优策略是贪心的：从左到右扫描并确保每个位置都成为`1`如果它比保留它更便宜`2`，使用附近未使用的`1`通过交换或直接覆盖。 交换仅在移动现有的时有用`1`比在该位置创建一个新的要便宜。 

因此我们保持可用`1`位置并将它们分配到最早需要的插槽，总是根据距离成本与重写成本选择最便宜的来源。

 ## 算法演练

 ## 分步过程

 1.提取该数字所在的所有索引`1`。 这些代表我们可以用来构建最终字符串的供应点。 
2. 我们从左到右处理位置，因为字典最小化强制首先确定较早的数字。 在每个位置我们决定它是否应该成为`1`。 
3. 对于每个位置`i`，我们考虑两种方法来实现`1`。 要么我们采用最接近的可用原始数据`1`并将其移动到这里，支付等于距离的交换成本，或者我们将这个位置重写为`1`直接与成本`c1`。 
4. 如果有最好的`1`距离太远，意味着交换成本超过`c1`，我们放弃交换并使用重写操作。 这确保了我们不会在远程移动上花费超过必要的费用。 
5. 如果我们选择使用交换，我们会将当前位置与最接近的可用位置配对`1`索引，删除它`1`从池中移出，并在概念上将其移至此处。 
6. 继续，直到所有职位均已处理或全部可用`1`已经筋疲力尽了。 剩余职位通过基于成本比较的重写决策来填补。 

### 为什么它有效

 在每个位置，我们都在解决“现有可用资源”之间的局部分配问题。`1`源”和“必需的前缀槽”。贪婪选择是有效的，因为交换成本随距离线性增长，任何非贪婪配对都会增加总移动距离或强制稍后进行额外重写。这会创建一个单调结构：较早的位置总是比较晚的位置更便宜或等于满足，因此延迟分配永远不会提高成本。不变的是处理位置后`i`，关于前缀的所有决定`[0, i]`考虑到剩余未使用的情况，成本最优`1`来源。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, K, c1, c2 = map(int, input().split())
    s = list(input().strip())

    ones = [i for i, ch in enumerate(s) if ch == '1']
    used = [False] * N

    ptr = 0
    res = ['2'] * N

    for i in range(N):
        if ptr < len(ones):
            j = ones[ptr]
            cost_swap = abs(i - j)
            if cost_swap <= c1:
                res[i] = '1'
                used[j] = True
                ptr += 1
            else:
                if c1 <= c2:
                    res[i] = '1'
                else:
                    res[i] = '2'
        else:
            if c1 <= c2:
                res[i] = '1'
            else:
                res[i] = '2'

    print("".join(res))

if __name__ == "__main__":
    solve()
```该实现首先收集所有位置`1`这样我们就可以将它们视为可重复使用的资源。 指针`ptr`确保我们总是消耗最接近的未使用的`1`按顺序，这符合之前的贪婪假设`1`s 应该服务于较早的目标位置。 

对于每个位置，我们将交换成本与重写成本进行比较`c1`。 如果交换更便宜，我们分配`1`到当前位置。 否则如果有益我们直接覆盖。 变量`used`包括在内以反映原始的消耗`1`s，尽管指针已经通过单调消耗保证了正确性。 

一个微妙的细节是`c2`只有在决定我们是否愿意离开这个职位时才重要`2`或转换它，但由于最终目标按字典顺序是最小的，我们只将其与`c1`当没有使用交换区时。

 ## 边缘情况

 一种边缘情况是，所有有益的交换都存在，但实际上没有一个是值得的，因为重写成本更便宜。 例如，如果`c1`较小并且指数相距很远，交换在系统上变得次优。 该算法通过直接比较交换距离来处理这个问题`c1`，防止昂贵的长链移动。 

另一个边缘情况是当有更多目标时`1`位置比可用的原始位置`1`s。 指针耗尽了池，算法完全切换到重写决策。 这避免了已消耗的无效重用`1`s 并确保最终前缀在成本限制下仍然按字典顺序最小。
