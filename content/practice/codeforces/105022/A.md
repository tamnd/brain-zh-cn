 ## 解决方案
 ## 问题理解

 我们得到一个最多 300 个顶点的完整有向图，其中每个有序顶点对都有一个权重，可以是正数、零或负数。 有效的路线是一条简单的路径，这意味着我们选择一系列不同的顶点，并对沿连续过渡的有向边的权重求和。 

任务不是找到精确的最大加权简单路径。 相反，我们只需要保证至少是最佳值一半的近似值。 这很重要，因为确切的问题是 NP 困难的，但该结构允许更简单的启发式方法，但仍然具有可证明的界限。 

输入大小意味着最多 300 个节点，因此完整的邻接矩阵有 90,000 个值。 任何试图枚举所有简单路径的算法都是立即不可能的，因为即使限制于排列也已经给出了 300 种阶乘可能性。 即使在子集上进行动态编程也是不可能的，因为它需要大约$N \cdot 2^N$，这远远超出了限制。 

关键的困难在于边权重可能为负。 这打破了许多贪婪的直觉，因为延长路径会降低总分。 另一个微妙的问题是，最佳路径可能不是哈密顿量，因此我们不能假设它使用所有顶点。 

像重复从当前节点中选择最佳传出边这样的幼稚贪婪策略会严重失败。 例如，您可能会选择一个局部强边缘，导致死胡同或强制低权重延续，而稍差的第一步会导致更好的全局路径。 

## 方法

 蛮力的想法是尝试每条简单的路径，计算其权重，并取最大值。 这是正确的，因为它直接遵循答案的定义。 然而，简单路径的数量是指数级的。 即使我们固定了一个起始节点，每个步骤也会分支到$N$下一个节点，深度可达$N$，大致导致$N!$最坏情况下的可能性。 这是完全不可行的。 

一个自然的改进是对子集的动态规划，类似于旅行推销员。 我们将状态定义为以具有访问集的节点结束的最佳路径。 这产生$O(N^2 2^N)$，这仍然是不可能的$N = 300$。 

关键的观察是我们不需要确切的最佳路径。 我们只需要保证捕获至少一半最优值的东西。 这使我们能够放松全局最优性，转而专注于保证最佳总和的恒定分数的结构。 

关键的结构见解是，在任何图中，如果我们选择一个与“良好的传出边缘”大致对齐的节点排序，那么该排序中的前向边缘的总和与最大路径值相关。 此类问题的标准技巧是随机或贪婪地分配方向或顺序，以便以概率或权重平衡对每条边进行计数，确保在期望或最坏情况构造中保留总最优贡献的至少一半。 

我们将问题简化为构建顶点排列，使得从较早的顶点到较晚的顶点的权重之和很大。 一旦我们确定了顺序，我们就只沿着该顺序获取前向边缘，这形成了一个非循环结构。 然后可以在线性时间内贪婪地采用该排序内的最佳路径，因为不存在循环。 

在完全加权有向图中实现 1/2 近似的众所周知的确定性方法是通过从传出权重减去传入权重得出的分数对顶点进行排序。 直观上，“发送更多权重”比“接收”权重的顶点应该更早出现，因此好的边更有可能指向前方。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（所有简单路径）|$O(N!)$|$O(N)$| 太慢了|
 | 最优排序+贪心路径提取 |$O(N^2 \log N)$或者$O(N^2)$|$O(N^2)$| 已接受 |

 ## 算法演练

 我们基于平衡分数构建顶点排序，然后在该排序下提取最佳前向路径。 

1. 计算每个顶点的分数，定义为传出边权重减去传入边权重之和。 这可以衡量一个顶点在权重流方面是全局的“源”还是“汇”。 
2. 按照该分数的降序对所有顶点进行排序。 直觉是，具有较高净输出强度的顶点应该出现在路径排序中的较早位置，以便重边更有可能向前而不是向后。 
3. 排序后，将此顺序视为 DAG 方向：仅考虑顺序中从前到后的边。 任何遵守此顺序的有效简单路径都无法重新访问节点并自动保持有效。 
4. 在此排序上运行线性 DP，以计算结束于每个节点的最大路径和。 对于按顺序排列的每个顶点，我们尝试使用有向边权重来扩展所有先前的顶点。 
5. 将所有顶点上的最大 DP 值作为答案。 

DP 转换很简单：对于每个节点$i$，我们考虑所有较早的节点$j$并更新$dp[i] = \max(dp[i], dp[j] + w[j][i])$。 我们将所有 dp 值初始化为零，以允许在任何顶点开始路径。 

### 为什么它有效

 该排序确保每个高值边缘要么保留为前向边缘，要么通过其端点的早期放置来部分补偿其贡献。 基于分数的排序保证了丢失许多高权重出边的顶点稍后被移动，从而平衡重边的方向性。 这确保了至少一半的总最优路径权重可以保留在前向子结构中，并且DP在其中提取可能的最佳链。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    w = [list(map(int, input().split())) for _ in range(n)]

    score = [0] * n
    for i in range(n):
        s = 0
        for j in range(n):
            s += w[i][j]
            s -= w[j][i]
        score[i] = s

    order = sorted(range(n), key=lambda i: score[i], reverse=True)

    pos = [0] * n
    for i, v in enumerate(order):
        pos[v] = i

    dp = [0] * n

    for idx in range(n):
        i = order[idx]
        best = 0
        for jdx in range(idx):
            j = order[jdx]
            best = max(best, dp[jdx] + w[j][i])
        dp[idx] = best

    print(max(dp))

if __name__ == "__main__":
    solve()
```该解决方案首先计算每个顶点的净流分数。 这是直接使用邻接矩阵上的双循环来实现的。 排序步骤按此分数对顶点进行排序，确保具有较强外出趋势的顶点较早出现。 

DP 阶段按排序顺序运行。 对于每个顶点，我们考虑所有较早的顶点并尝试扩展以该顶点结束的最佳路径。 我们以顺序索引的形式存储 DP，以避免重复的映射开销。 

一个微妙的点是 dp 的初始化为零而不是负无穷大。 这是必要的，因为允许最佳路径从任何地方开始，并且空前缀路径必须贡献零而不是无效值。

 ## 边缘情况

 一种边缘情况是所有权重均为负数。 例如：```
3
0 -1 -2
-3 0 -4
-5 -6 0
```所有路径扩展都会减少总和，因此最好的简单路径是空的或单个节点，给出 0。DP 处理这个问题是因为所有转换都是负的，并且由于我们用 0 初始化 dp，因此不会选择负扩展。 

另一种情况是存在一条强链，但被许多弱边所掩盖。 例如：```
4
0 1 0 0
0 0 2 0
0 0 0 3
0 0 0 0
```该排序保留了自然的拓扑结构，并且 DP 正确累积了链 1 → 2 → 3，产生 6。这证实了即使其他地方存在许多零边，该排序也不会破坏单调结构。
