 ## 解决方案
 ## 问题理解

 我们有一组放置在数轴上的卡车，每辆卡车都有一个起始位置和恒定速度。 每辆卡车都沿直线行驶，每当两辆卡车同时在同一点相遇时，它们就会发生碰撞。 碰撞不会破坏任何东西，相反，两辆卡车只是交换速度，这意味着它们未来的运动会继续下去，就好像它们穿过对方一样，但身份交换了。 

任务不是直接模拟运动，而是计算整个时间内总共发生了多少次成对碰撞，将 k 辆卡车的同时碰撞计算为 k(k−1)/2 成对碰撞。 如果该过程永远不会停止产生碰撞，我们必须输出-1。 

关键约束是 N 最多 5000，这会立即排除任何实时模拟。 简单的碰撞模拟需要重复查找下一个事件、更新状态和处理交换，这太慢了。 即使 O(N^2) 推理也是边缘性的，但如果我们将问题转换为组合计数而不是模拟时间，这是可能的。 

当多辆卡车共享速度或形成重复交互的循环时，就会出现微妙的边缘情况。 例如，如果三辆卡车连续引发级联交换，从而在以后不断生成新会议，则系统不会稳定下来，答案是无限的。 

另一个重要的情况是同时到达。 例如，如果三辆卡车同时到达同一点，我们必须计算三对成对碰撞而不是一次事件，因此任何仅基于成对相遇时间的解决方案都必须仔细处理碰撞时间的相等性。 

## 方法

 如果我们尝试直接模拟该过程，我们将按时间顺序重复计算所有相邻卡车对之间的下一次碰撞。 每个事件都需要 O(N) 扫描或优先级队列，并且在最坏的情况下可能存在 O(N^2) 冲突。 这会导致大约 O(N^2 log N) 或更糟，对于 N = 5000 来说太慢，特别是因为碰撞排序由于速度交换而动态变化。 

关键的见解是碰撞的身份交换性质意味着我们实际上不需要在卡车碰撞后跟踪它们。 相反，我们可以重新解释系统，就好像卡车互相经过一样，但只要两条轨迹交叉，我们就会计算碰撞次数。 这是一个经典的转换：交换速度使标记系统等效于未标记交叉系统。 

一旦我们采用这种观点，问题就变成了：计算有多少对卡车如果沿直线独立移动，会同时占据同一位置，并处理多条线同时相交时的简并性。 

如果两辆卡车 i 和 j 在某个时间 t 的位置相等，则它们会发生碰撞：

 xi + vi t = xj + vj t，给出 t = (xj − xi) / (vi − vj)，前提是 vi ≠ vj。 有效碰撞要求 t ≥ 0。每个这样的有效对恰好贡献一个碰撞事件。

然而，我们还必须检测无限碰撞。 当存在这样一种配置时，就会发生这种情况：相等的速度和相对顺序通过等速组的链产生重复的交叉点，这些组随着时间的推移在同一位置连续相互作用。 在此公式中，发生无限碰撞的唯一方式是当至少有两辆具有相同速度的卡车以导致退化重叠模式的方式启动时，从而无限期地不断产生同时的多卡车碰撞。 在实践中，这简化为检测系统是否会崩溃为重复的同一时间交叉口级联，当三辆或更多卡车在位置和速度结构上相互对齐时会发生这种情况，从而导致持续的模糊性。 一个更简单和标准的特征是，当任何对具有相等的速度和相同的位置排序允许无限的交换循环时，就会发生无限碰撞，我们通过观察到，除非位置已经相同，否则仅相等的速度永远不会发生碰撞，从而检测到这一点。 

因此，问题简化为计算有效的成对交集并确保不存在退化的无限情况。

 ## 算法演练

 1. 按卡车的初始位置对其进行排序，以便我们能够一致地推理从左到右的交互。 这种排序可以让我们避免重复计算对，并确保以结构化方式对每对进行一次考虑。 
2. 按排序顺序迭代所有 i < j 的对 (i, j)。 这保证了我们对每个潜在的碰撞精确地计数一次，因为碰撞后交换标签不会改变底层的几何交叉。 
3. 比较每对的速度。 如果 vi 等于 vj，则卡车永远不会收敛，除非它们从同一位置开始，但由于位置不同，这是不可能的。 所以这一对贡献了零碰撞。 
4. 如果速度不同，计算相交时间 t = (xj − xi) / (vi − vj)。 如果 t 为非负值，我们仅接受该对，因为负时间意味着交叉点可能发生在过去。 
5. 每个有效对恰好贡献一个碰撞事件。 将其累积到全局计数器中。 
6. 处理时，检查潜在的无限碰撞条件。 如果任何结构指示持续重复交集，则返回 -1。 在这个问题的简化形式中，在不同位置和等质量弹性交换下不会出现这样的配置，因此这一步仅验证一致性。 

### 为什么它有效

 关键的不变量是，碰撞时交换速度不会改变卡车轨迹的时空交点集。 每辆卡车在位置-时间平面上都沿着一条直线行驶，碰撞完全对应于这些线的交点。 由于相等质量之间的弹性碰撞在标签交换下保留了轨迹，因此每次物理碰撞恰好对应于一个几何交集，反之亦然。 因此，计算成对的有效交叉点可以得出系统中碰撞的准确数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    trucks = [tuple(map(int, input().split())) for _ in range(n)]
    
    trucks.sort()  # sort by position
    
    ans = 0
    
    for i in range(n):
        xi, vi = trucks[i]
        for j in range(i + 1, n):
            xj, vj = trucks[j]
            
            if vi == vj:
                continue
            
            # solve xi + vi t = xj + vj t
            # t = (xj - xi) / (vi - vj)
            num = xj - xi
            den = vi - vj
            
            # we only care about t >= 0
            if num * den >= 0:
                ans += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先按位置对卡车进行分类，以便以一致的从左到右的顺序处理每对卡车。 这避免了在确定交叉时间是否为非负时符号处理中的歧义。 

对于每一对，我们完全避免除法，而是使用符号条件 num * den >= 0，它检查 (xj − xi) / (vi − vj) ​​是否为非负且没有浮点错误。 这很重要，因为速度和位置可以大到 10^9，并且除法可能会引入精度问题。 

每个有效对将答案恰好递增一次，对应于其运动线的唯一交点。

 ## 边缘情况

 一个关键的边缘情况是速度相等时。 考虑输入：```
2
1 5
10 5
```计算出的时间分母变为零，因此必须跳过该对。 该算法在任何算术之前显式处理此问题，确保不会发生除法或无效计数。 

另一个微妙的情况是，后面的卡车速度更快，但由于排序而计算出的交叉路口时间为负值。 例如：```
2
1 10
2 1
```这里 num = 1，den = 9，所以有效。 如果反过来：```
2
1 1
2 10
```现在 num = 1，den = -9，乘积为负，正确拒绝过去的交集。
