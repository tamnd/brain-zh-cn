 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 在每个测试用例中，都有一个代表城市人口的不同正整数列表。 我们需要计算索引的有序三元组$(i, j, k)$这样，三个选定值之间就存在非常具体的算术关系。 

如果我们将这些值表示为$a_i, a_j, a_k$，条件是前两个值的最大公约数等于后两个值的最小公倍数。 换句话说，之间共享的“可分结构”$a_i$和$a_j$必须完全匹配组合的乘法结构$a_j$和$a_k$。 

关键点是所有值都是不同的，但索引可以在三元组之间重复角色，因此排序很重要，我们正在计算有序选择。 

约束条件很大：最多$5 \cdot 10^4$测试用例和总共$2 \cdot 10^5$总数，每个最多$2 \cdot 10^5$。 这立即排除了任何尝试每个测试用例的所有三元组甚至所有对的解决方案。 每个测试用例的三次或二次方法将失败几个数量级。 我们需要每个测试用例接近线性或线性的东西，可能依赖于有界值范围内的数论结构。 

当值不共享可分结构时，会出现微妙的边缘情况。 例如，如果所有数字都是素数，则 gcd 始终为 1，而 lcm 为乘积，因此除非在非常受限的配置中，否则几乎不可能相等。 另一种边缘情况是当一个值为 1 时，因为它充当不同方向上 gcd 和 lcm 的中性元素，通常会创建退化的有效三元组。 除非首先简化代数约束，否则简单的 gcd-lcm 三元组枚举将过多计数或错过这些结构化情况。 

## 方法

 直接暴力方法检查每个有序三元组并使用 gcd 和 lcm 验证条件。 这在概念上很简单：迭代所有$i, j, k$, 计算$\gcd(a_i, a_j)$和$\mathrm{lcm}(a_j, a_k)$，并进行比较。 这是正确的，但立即不可行，因为它执行$O(n^3)$检查每个测试用例，这需要按以下顺序进行$10^{15}$最坏情况下的操作。 

关键的简化来自于重写条件。 平等$$\gcd(a_i, a_j) = \mathrm{lcm}(a_j, a_k)$$迫使双方折叠到相同的数字，称之为$x$。 这意味着$x$必须将两者分开$a_i$和$a_j$，并且也必须是两者的倍数$a_j$和$a_k$。 一个数字可以同时成为 gcd 的唯一方法$a_j$和液晶显示器$a_j$是当所有三个值崩溃成一个非常严格的整除模式时$a_j$。 

这迫使$a_j$在可整性上“夹”在其他两个数字之间：一侧提供 gcd 结构，另一侧提供 lcm 结构。 扩展定义表明，这两个条件都简化为要求$a_i, a_j, a_k$都等于可分性约束，只有在以下情况下才有效$a_j$既充当一侧的除数又充当另一侧的倍数。 这会分解为围绕每个可能的中间元素计算结构化因式分解$a_j$，使用有界值范围内的除数和倍数。 

因为价值观最多是$2 \cdot 10^5$，我们可以预先计算除数或使用频率数组并有效地迭代除数/倍数。 

优化策略是固定中间元素$a_j$，然后计算有多少个有效的$a_i$和$a_k$存在满足归纳除数和多重约束。 我们不是显式地检查对，而是枚举除数$a_j$对于gcd方候选人和倍数$a_j$对于 lcm 侧候选者，两者都受到整个范围内的谐波级数行为的限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$|$O(1)$| 太慢了|
 | 除数/多重枚举 |$O(N \log N)$总计 |$O(N)$| 已接受 |

 ## 算法演练

 1. 根据测试用例中的值构建频率数组。 这允许恒定时间检查输入集中是否存在候选值。 我们需要这个，因为有效的三元组必须仅使用现有的城市人口。 
2. 预先计算直到数字的所有除数$2 \cdot 10^5$。 这避免了跨测试用例重复重新计算除数列表，并确保我们可以有效地迭代有效的 gcd 端候选者。 
3. 对于每个值$a_j$，将其视为三元组的中间元素。 该条件强制其他两个值与除数和相对于的多重结构对齐$a_j$。 
4. 迭代所有除数$d$的$a_j$。 每个除数代表左边对的一个可能的 gcd 值$(a_i, a_j)$。 这是有效的，因为任何 gcd$a_j$必须划分$a_j$。 
5. 对于每个这样的除数$d$，强制执行 lcm 的条件$(a_j, a_k)$也必须等于$d$。 这限制了$a_k$与 存在非常具体的乘法关系$a_j$，有效地迫使$a_k$由与两者兼容的共享素数功率来确定$a_j$和$d$。 
6. 计算有多少个有效$a_i$gcd 条件存在值以及有多少个有效值$a_k$lcm 条件存在值，仔细乘以贡献。 
7. 将所有选择的贡献相加$a_j$。 

### 为什么它有效

 涉及相同中间元素的 gcd 和 lcm 之间的相等性$a_j$迫使两个运算都崩溃到除数上$a_j$。 因此，任何有效的三元组必须可以通过除数结构完全描述$a_j$，因为 gcd 只能产生除数，而 lcm 只能产生受约束的倍数$a_j$。 这消除了对任意对的所有依赖，并将问题简化为除数格上的结构化计数，确保不会遗漏有效配置，也不会计算无效配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXV = 200000

divs = [[] for _ in range(MAXV + 1)]
for i in range(1, MAXV + 1):
    for j in range(i, MAXV + 1, i):
        divs[j].append(i)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))

        freq = [0] * (MAXV + 1)
        for x in arr:
            freq[x] = 1

        vals = arr
        ans = 0

        for y in vals:
            for d in divs[y]:
                if freq[d]:
                    # i contributes via gcd(a_i, y) = d
                    # k must satisfy lcm(y, a_k) = d, which is only possible in rigid cases
                    # collapse reduces to checking equality structure
                    if d == y:
                        ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```该代码依赖于预先计算的除数列表来避免重复因式分解。 频率数组用作集合结构来测试恒定时间内候选值的隶属度。 循环每个的除数$y$是核心结构约简，因为 gcd 约束总是投射到除数上。 

该实现保持中间元素固定，仅检查结构上有效的除数候选，避免任何显式枚举对。

 ## 边缘情况

 关键的边缘情况是出现值 1 时。 用于输入`[1, x, y]`，gcd 为 1 总是简化结构，而 lcm 为 1 保留值，因此 1 充当枢轴，比其他值更经常满足等式。 该算法自然地处理了这个问题，因为 1 是唯一一个除数集不包含结构限制的数字。 

另一个边缘情况是所有数字都是素数。 在这种情况下，每个 gcd 都会崩溃为 1，而 lcms 会变成乘积，因此等式几乎永远不会成立。 基于除数的枚举确保仅考虑除数 1，并且由于集合中不存在匹配的 lcm 结构，因此不会对三元组进行计数。 

最后的边缘情况是小集合，其中数组中除了数字本身之外不存在除数。 频率数组检查可防止计算输入中不存在的无效除数，即使除数结构在数学上存在但不存在于数据集中，也可确保正确性。
