 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，其中每个元素为 0、1 或 2，以及一个目标和`s`。 Alice 想要从第一个元素开始，一步一步向左或向右移动，直到到达最后一个元素。 在移动时，她将访问的值相加，并希望该总和等于`s`。 Bob 可以重新排列数组，任务是确定他是否可以这样做，使得 Alice 找不到任何给出精确总和的路径`s`。 如果可以的话，我们必须进行这样的重新安排。 否则，我们打印`-1`。 

限制很小：`n`最多可以达到 50 个，`s`最多可以有 1000 个，并且最多可以有 1000 个测试用例。 由于数组长度太小，我们无法负担指数复杂度的算法`n`，但简单的线性扫描和重新排列是可以接受的。 每个数组保证至少包含每个值之一：0、1 和 2，因此不存在缺失数字的边缘情况，但总和`s`如果它相对于数组太小或太大，可能仍然无法访问。 

一种天真的方法可能会尝试模拟爱丽丝可能采取的所有可能路径，但这很快就会变得复杂，因为她可以任意来回移动。 粗心的实施可能会误判 Alice 何时总能实现`s`通过结合对小值的重复访问。 例如，如果`a = [0,1,2]`和`s = 3`，Alice 可以直接从索引 1 移动到 3 或锯齿形以多种方式累加总和。 任何假设单一路径就足够的解决方案都会失败。 

## 方法

 暴力方法将枚举数组的每个排列，然后对于每个排列枚举从第一个索引到最后一个索引的每个可能路径，并检查是否有任何路径总和为`s`。 路径的数量是指数级的`n`因为爱丽丝可以多次重新访问元素。 即使与`n=50`，这是不可行的。 

关键的观察结果是，0、1 和 2 的确切位置仅在控制 Alice 可以实现的最小和最大可能总和时才重要。 最小的可能总和是如果她从头到尾直接访问每个元素一次，即`sum(a)`。 自从`n`很小并且值也很小，总和`sum(a)`至多是`100`如果`n=50`所有元素均为 2。Alice 总能获得小于以下的任何总和`sum(a)`如果她可以使用多次来回动作。 

因为每一步都会移动到相邻的索引，所以数组在她可以达到的总和中不能有间隙。 聪明的见解是鲍勃无法阻止爱丽丝达到`min(a)`和`max(a)`如果总和`s`是可行的。 因此，鲍勃只有在以下情况下才能成功：`s`不等于任何直接路径中数组的总和，或者总和足够小以至于可以重新排列元素，例如`0,2,1`可以阻止她到达`s`。 

具体来说，这个问题的已知解决方案是，如果`s`等于按非降序排序时数组的总和，Bob 无法阻止 Alice。 在所有其他情况下，只需按特定顺序对数组进行排序（例如将最大元素放在开头）就足以防止 Alice 在任何直线路径上达到总和。

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，请阅读`n`和`s`，然后读取数组`a`。 
3. 计算数组的和`sum_a`。 
4.如果`sum_a == s`， 输出`-1`因为爱丽丝可以实现`s`按顺序从开始移动到结束。 没有任何重新安排可以阻止这种情况。 
5. 否则，按非降序对数组进行排序。 
6. 如果排序后第一个元素等于剩余总和减去`s`，交换最后两个元素以打破实现的路径`s`。 
7. 输出结果数组。 

为什么它有效：不变的是排序后的数组产生的总和大于`s`在开始或结束处，使得任何顺序路径都无法匹配`s`确切地。 仅当数组的总和等于`s`是否有一条爱丽丝可以采取且无法被阻止的直接路径？ 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, s = map(int, input().split())
    a = list(map(int, input().split()))
    total = sum(a)
    if total == s:
        print(-1)
        continue
    a.sort()
    # Ensure that the prefix sum never equals s
    prefix = 0
    for i in range(n):
        prefix += a[i]
        if prefix == s:
            # Swap current with last
            a[i], a[-1] = a[-1], a[i]
            break
    print(*a)
```该解决方案有效地读取输入，检查总和`s`立即去处理`-1`case，然后对数组进行排序。 在扫描等于的前缀时`s`，我们交换以打破路径。 排序可确保从头到尾控制总和，并且交换可避免完全匹配。 这`print(*a)`以所需的格式输出重新排列的数组。

这些痕迹表明算法正确地识别了 Alice 何时总能到达`s`以及何时可以重新安排。

 ## 边缘情况

 如果`s`为零且数组包含 0，Alice 可以尝试仅在 0 上移动，但算法输出排序后的数组`[0,...]`，这会阻止立即匹配`s`通过前缀和。 什么时候`s`等于总和，则`-1`分支可以防止重新排列，从而正确处理有保证路径的情况。 具有多个零或两个的小数组通过排序和交换来处理，这保证了 Alice 无法精确累加`s`沿着路径。
