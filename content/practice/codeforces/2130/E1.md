 ## 解决方案
 ## 问题理解

 在原始交互问题中，有一个隐藏的括号序列，其中包含`'('`和`')'`。 我们可能会询问所选位置的查询，并且判断器返回构造的字符串中常规括号子串的数量。 目标是在查询限制内重建整个隐藏序列。 

对于 Codeforces 上使用的黑客版本，交互被删除。 完整的括号序列直接在输入中给出。 接受的提交只需输出相同的序列。 

尽管黑客版本的实现很简单，但问题的有趣部分是激发原始解决方案的交互策略。 简单版本允许最多 550 个查询，而长度最多为 1000 个。由于逐个重建 1000 个字符的成本太高，因此每个查询必须一次显示多个位置的信息。 

交互版本中的一个微妙情况是序列中不包含`"()"`根本不。 例如：```
))))(((
```每一个`'('`出现在每个之后`')'`。 任何假设存在相邻的策略`"()"`配对立即失败。 官方的解决方案是单独处理这种情况的。 

另一种不明显的情况是当第一个正则子串第一次​​出现在某个位置时`i`。 人们可能会倾向于得出这样的结论：存在一个以`i`，但这意味着更早存在更小的正则子串，这与极小性相矛盾。 这一观察结果是找到有保证的关键`'('`和`')'`。 

## 方法

 暴力交互的思想是独立确定每个位置。 一旦我们知道其中一个已确认`'('`和一位确认`')'`，单个查询可以对一个未知位置进行分类。 对于长度为 1000 的序列，这大约需要 1000 次查询，这超出了 550 次的限制。 

成功的方法使用两个观察结果。 

首先，我们可以找到一个已知的左括号和一个已知的右括号，仅用`O(log n)`查询。 让`pref(i)`表示为前缀返回的值`s[1..i]`。 我们二分查找前缀包含常规子串的最小位置。 

如果存在这样的位置，则位置`i - 1`和`i`必须是`"()"`。 否则序列不包含`"()"`任何地方，这迫使形式```
))))...((((
```因为每个右括号必须出现在每个左括号之前。 

二、一旦确认`'('`和一位确认`')'`众所周知，精心构建的查询可以同时确定两个未知字符。 使用字符串```
((()()ab
```在哪里`a`和`b`是两个未知位置，四种可能的分配产生四个不同的答案：

 |`ab`| 查询值|
 | --- | --- |
 |`((`| 3 |
 |`)(`| 4 |
 |`))`| 5 |
 |`()`| 6 |

 由于每个结果都是唯一的，因此一个查询可以完全确定这两个字符。 

这将重建成本降低到大约`n / 2`初始二分搜索后的查询，很容易符合限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n) 个查询，每个查询一个字符 | O(1) | O(1) | 查询太多 |
 | 最优交互策略| O(log n + n/2) 次查询 | O(1) | O(1) | 已接受 |
 | 破解版 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 ### 原创互动解决方案

 1.二分查找最小索引`i`这样前缀`s[1..i]`至少包含一个常规子串。 
2. 如果不存在这样的索引，则序列不包含`"()"`。 由于两种括号类型都保证出现，因此位置`1`是`')'`和位置`n`是`'('`。 
3. 其他职位`i - 1`和`i`形式`"()"`。 使用它们作为已知的参考位置：

 -`open = i - 1`-`close = i`4. 成对处理未知位置。 
5. 对于职位`a`和`b`，查询对应的索引序列：```
((()()ab
```从已知的构建`open`和`close`职位。 
6. 返回值唯一标识该对：

 | 价值| 人物 |
 | --- | --- |
 | 3 |`((`|
 | 4 |`)(`|
 | 5 |`))`|
 | 6 |`()`|
 7. 如果一个位置仍未配对，请将其与已知的结束括号进行比较。 查询值立即判断是否为`'('`或者`')'`。 

### 为什么它有效

 让`i`是第一个值为正的前缀。 

结尾为的常规子字符串`i`必须存在。 如果该常规子字符串的长度大于 2，则其内部本身将包含完全位于较早前缀内的常规子字符串`s[1..i-1]`。 这与选择相矛盾`i`。 因此第一个正则子串必须恰好是`"()"`，所以位置`i-1`和`i`是已知的。 

在获得一个已确认的左括号和一个已确认的右括号后，构建的小工具`((()()ab`产生四个不同的值。 由于每一个可能的分配`a`和`b`映射到不同的答案，每个查询唯一地标识这两个字符。 

## Python 解决方案

 对于黑客版本，输入中已提供序列。 所需的输出只是相同的序列。```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    s = input().strip()
    print(s)
```实现故意很短，因为交互组件不以黑客格式存在。 

第一行给出了测试用例的数量。 对于我们阅读的每个测试用例`n`，然后读取括号序列本身，并按原样打印它。 

不需要重构逻辑，因为原始问题的隐藏信息已经在输入中暴露出来。

# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:

 ## 边缘情况

 考虑：```
1
2
()
```该序列已包含两种括号类型。 该程序只是回应它。 无需特殊处理。 

考虑：```
1
2
)(
```这是另一种最小长度的可能性。 程序再次输出未更改的序列。 

考虑：```
1
8
))))((((
```在原始的交互问题中，这是特殊的配置，没有`"()"`任何地方的子串。 官方解决方案必须单独对待。 在破解版本中，序列是直接提供的，因此打印它就足够了。 

考虑：```
1
8
(()())()
```高度结构化的规则序列。 被黑客攻击的解决方案不依赖于任何括号属性，并完全按照给定的方式输出。
