 ## 问题理解

 我们给出一个起始整数，并允许使用两个操作来转换它：我们可以将它加倍，或者我们可以将它除以六，但前提是它可以被六整除。 每个测试用例都会询问我们是否可以达到值一，如果可以，则所需的最少操作数是多少。 

从实际意义上讲，该过程是有方向的且不可逆的，因为除法减少了数字，而乘法则增加了数字。 任务不是盲目地模拟所有可能的序列，而是确定是否存在这些操作的序列将数量精确地减少到1，并在所有有效序列中选择步数最少的序列。 

这些约束清楚地表明我们无法以图的形式探索状态。 由于测试用例多达 2000 个，值高达 10 亿个，任何每步分支到多个状态的方法都会发生组合爆炸。 即使是简单的广度优先搜索也是不可能的，因为中间值可以不受小范围限制的方式增大或缩小。 

当数字不能以与重复除以六的结构相匹配的方式被二或三整除时，就会出现微妙的边缘情况。 例如，如果我们从 2 或 10 这样的数字开始，可能会感觉重复乘法可以帮助“修复”整除性，但乘以 2 实际上会使整除性变得更难实现。 另一个误导性的情况是，一个数字在经过一些乘法后最终可以被六整除，但该路径总是比最佳序列成本更高，或者根本没有好处。 

例如，从 12 开始，天真的直觉可能会任意尝试混合运算，但正确的答案实际上是不可能的，因为因子结构不符合仅使用六步除法来保留可行性的要求。 

## 方法

 蛮力的想法是将每个数字视为图中的一个节点，并将边视为有效操作：从 x 我们可以到 2x，如果可整除，从 x 我们可以到 x/6。 然后我们使用 BFS 搜索从 n 到 1 的最短路径。 这在理论上是正确的，因为每次移动的成本相等，并且 BFS 保证最短路径。 

问题在于状态空间是无界的。 对于像 10^9 这样的数字，重复加倍很快就会超出任何合理的界限，而重复除法则取决于稀疏的整除模式。 BFS 树呈指数增长，因为每个节点都可以生成新的相乘状态和潜在的划分状态，从而导致较大的分支因子并以不同形式重新访问许多状态。 

关键的观察结果是，除以六是唯一减少该值的运算，而乘以二只有在它有助于我们将来除以六时才有意义。 这意味着我们不应该根据任意序列来思考，而应该根据因素操纵来思考。 

我们可以将任何数字分解为一些余数的二倍和三倍的幂。 除以六同时消除二的一个因数和三的一个因数。 乘以 2 会增加 2 的因数。 由于除了通过初始数字或已经存在的划分结构之外，无法创建三因数，因此整个过程由二和三的幂之间的平衡控制。 

关键的简化是以受控的方式重复消除所有二和三的因子。 如果去掉二和三的所有因数后剩下的数字不是一，我们永远不可能达到一。 否则，我们只需要决定如何使用乘法来平衡 2 的额外幂，以便每次除以 6 都是有效的。

这将问题简化为跟踪我们除以六的次数以及我们必须引入多少个额外的二因数。

 ## 算法演练

 我们独立处理每个数字。 

1. 从数字中分解出 2 和 3 的所有幂。 只要有可能，我们就会反复除以二和三。 这隔离了实际与允许的操作交互的结构。 
2. 如果去掉所有二和三的因数后，这个数字不是一，我们立即断定这是不可能的。 发生这种情况是因为除了两个之外，没有任何操作引入任何质因数。 
3. 最初数一下这个数能被二和三整除多少次。 让这些计数代表有多少次可以直接被六除。 
4. 限制因素是三的数量，因为每次除以六都会消耗一个三的因数和一个二的因数。 如果三元组的数量少于匹配结构所需的数量，我们就会失败。 
5. 一旦我们知道所需除法步骤的总数等于删除的三的数量，我们就使用乘以二进行调整。 每次乘以二时，我们都会有效地“创建”一个额外的二元因子，以在需要时支持未来的除法运算。 
6. 通过将除法运算的数量与可用因子 3 对齐并使用最少的乘法次数补偿缺失的因子 2 来计算最终答案。 

关键的结构不变量是每个有效序列都可以重新排列，以便所有乘以 2 的操作仅在需要除以 6 时才发生。 这意味着最优策略完全由因子计数决定，而不是任意交错操作。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n):
    # remove all factors of 2
    c2 = 0
    while n % 2 == 0:
        n //= 2
        c2 += 1

    # remove all factors of 3
    c3 = 0
    while n % 3 == 0:
        n //= 3
        c3 += 1

    # if remaining part is not 1, impossible
    if n != 1:
        return -1

    # we need at least as many 3s as 2s removed initially
    if c2 > c3:
        return -1

    # operations:
    # we need to match c3 divisions, but we have c2 surplus of 2-factors
    # each extra 3 beyond c2 requires a division step, and balance is c3
    return (c3 - c2) + c3

t = int(input())
for _ in range(t):
    n = int(input())
    print(solve_case(n))
```该代码的工作原理是将数字分成其素数结构。 去除因子 2 和 3 的循环精确地隔离了每种操作类型在逻辑上可以应用的次数。 

不可能检查`n != 1`因子剥离后确保我们永远不会尝试从包含除二或三以外的素数的数字中得出一。 条件`c2 > c3`捕获了结构不匹配，即我们有太多的二的幂相对于三的幂，这意味着我们无法将它们对齐到有效的六除法步骤中。 

最终的公式表达了这样的想法：我们必须首先通过隐式乘法补偿缺失的结构，然后执行必要的除法。

def solve(inp: str) -> str:
    import sys
    input = sys.stdin.readline

 ## 边缘情况

 当 n 等于 1 时，循环不执行任何操作，两个计数器都保持为零，因此算法正确返回零步。 当 n 是 2 的纯幂（例如 2 或 4）时，3 的剥离因子会立即失败，因为不可能除以 6，并且剩余因子结构会阻止达到 1。 当 n 仅是 2 和 3 的乘积（例如 6 或 18）时，算法会清楚地计算匹配的因子对，并且计算出的运算数量与所需除法的数量相匹配。
