 ## 解决方案

 ## 问题理解

 我们得到一个正整数数组。 我们可以执行一系列的移动，每个移动都会推进一个全局计数器`x`从零开始。 在每一步中，我们要么跳过或“使用”当前值`x`在恰好一个数组位置上，添加`x`到那个元素。 无论选择哪一个之后，`x`增加一。 每个索引最多可以接收一次该“使用”操作。 

目标是使每个数组元素都可以整除`k`。 在该条件成立之前，我们需要最少的移动次数。 

解释该过程的一个有用方法是，时间通过以下值确定性地进展：`x = 0, 1, 2, ...`。 每次我们都可以将当前值分配给一个未使用的索引，但也允许跳过。 每个索引（如果选择）都会接收一个带时间戳的加法，并且该加法值在我们选择它时固定。 

约束条件`n ≤ 2·10^5`在所有测试用例中意味着我们需要大致线性或`O(n log n)`每个测试用例最坏的行为。 随着时间的推移检查所有时间表或 DP 之类的任何事情都是不可能的，因为`x`可以增长任意大，并且模拟长度在朴素形式下是无限的。 

贪婪思维产生了一个微妙的问题：尽快选择指数并不总是最优的，因为稍后的值`x`更大，对于某些残留物可能更“有用”。 例如，如果多个索引可以在同一时间步长固定在一起，则延迟选择可以减少所需的总移动次数。 

另一个边缘情况是某些元素已经可以被整除`k`。 这些不需要任何操作，但它们仍然与调度交互，只是我们不应该给它们分配任何移动。 

最后，该过程仅取决于余数模`k`，因为我们只关心整除性。 大值可以减少为`a_i % k`，并且每个操作都会添加一个唯一的整数时间戳。 

## 方法

 暴力解释将逐步模拟时间。 在每个`x`，我们决定是否将其分配给某个未完成的指标，其剩余赤字可以得到满足，跟踪所有可能性。 这很快就会呈指数增长，因为在每一步都有很多应用索引的选择`x`到，并且跳过也会分支状态空间。 即使是尝试在可能的情况下总是进行分配的贪婪模拟也会失败，因为未来大量的可用性`x`值会影响最佳配对。 

关键的观察是扭转视角。 我们不考虑为索引分配时间戳，而是考虑每个索引需要多少“额外增量”才能达到`k`。 每个索引都有所需的余数赤字`d_i = (k - a_i % k) % k`。 如果`d_i = 0`，已经完成了。 

现在观察一项作业的作用：选择时间`x`准确贡献`x`一个指数赤字的单位。 所以每个索引需要匹配一个唯一的整数`x`这样所选的总和`x`分配给它的值等于它的赤字。 由于每个索引仅采用一个值，因此每个索引本质上都分配有一个数字。 

这将问题转化为对相同的“需求”进行分组，这些“需求”可以通过选择相同的选项来满足`x`。 然而，有一个关键的相互作用：如果多个指数有相同的赤字`d`，我们不能总是给它们分配相同的值`x`自由地因为`x`是全局且严格递增的。 如果我们多次分配相同的余数类，我们必须确保存在足够的时间步长`x % k`匹配所需的结构。 

关键的简化来自配对赤字：如果赤字值`d`需要多次，最佳策略是多次调度它们，形成周期序列模`k`，成本取决于发生的重复次数。 具体来说，对于一个频率`f`对于给定的余数类，我们需要`f`出现次数间隔为`k`，导致最后一次出现在位置`d + (f-1)·k`。 

因此对于每个不同的赤字`d`，我们计算最后一次到达该组的时间。 答案是最后所需时间的所有组的最大值加一（因为移动是 0 索引的时间步长）。 

这将问题转化为计算赤字频率并计算每个桶的简单公式。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 将每个元素的赤字计算为`d = (k - a_i % k) % k`。 这告诉我们每个元素还需要多少才能达到`k`。 元素与`d = 0`被忽略，因为它们不需要任何操作。 
2. 计算有多少个元素共享每个赤字值。 我们将其存储在频率图中。 
3. 对于每个赤字值`d`随频率`f`，计算完成该组中所有元素所需的时间：`time = d + (f - 1) * k`。 推理是在使用了价值贡献之后`d`，相同结构的下一个可用出现每隔`k`由于模循环限制而产生的步骤。 
4. 跟踪最大值`time`涵盖所有赤字群体。 
5. 如果不存在非零赤字，则答案为零。 否则，答案是`max_time + 1`，因为我们从开始计算移动`x = 0`。 

### 为什么它有效

 各项指标均出现赤字`d`必须恰好接收一个有助于修复其余数的时间戳值。 因为时间戳严格增加并以模换行`k`，兼容贡献的出现每隔一次重复一次`k`步骤。 如果出现赤字值`f`次，我们不能在`(f-1)`- 重复该模类，强制最后一次赋值至少发生`d + (f-1)·k`。 由于我们只需要所有组的最新完成时间，因此这些界限的最大值给出了所需的最小移动数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        freq = {}
        for v in a:
            r = v % k
            if r == 0:
                continue
            d = k - r
            freq[d] = freq.get(d, 0) + 1

        if not freq:
            print(0)
            continue

        ans = 0
        for d, f in freq.items():
            last_time = d + (f - 1) * k
            ans = max(ans, last_time)

        print(ans + 1)

if __name__ == "__main__":
    solve()
```该解决方案首先将每个数字压缩为其所需的余数调整。 只有非零调整很重要，因为这些元素已经有效。 然后我们汇总有多少元素需要相同的调整。 

关键计算是`d + (f - 1) * k`，它编码了这样一个事实：随着时间的推移，相同的缺陷会竞争相同的残留类别。 决赛`+1`考虑将最后时间索引转换为移动计数。 

必须注意不要错误地重置每个余数模的频率，因为`d`不是`r`，但它的补充`k`。 混合这些会导致错误的分组。 

## 工作示例

 我们追踪两种情况：一种是小情况，另一种是分组很重要的情况。 

### 示例 1

 输入：```
n=4, k=3
a = [1,2,1,3]
```赤字：

 | 我| a_i % 3 | d = (3 - r) % 3 |
 | --- | --- | --- |
 | 1 | 1 | 2 |
 | 2 | 2 | 1 |
 | 3 | 1 | 2 |
 | 4 | 0 | 0 |

 频率图变为`{2:2, 1:1}`。 

现在计算时间：

 | d | f | 最后时间 = d + (f-1)*k |
 | --- | --- | --- |
 | 2 | 2 | 2 + 3 = 5 | 2 + 3 = 5
 | 1 | 1 | 1 |

 最大值为`5`，答案是`6`。 

这符合赤字 2 组由于出现两次而受到更多限制的想法。 

### 示例 2

 输入：```
n=5, k=4
a = [1,1,1,1,1]
```余数均为 1，因此所有赤字均为 3。 

频率图`{3:5}`。 

| d | f | 上次 |
 | --- | --- | --- |
 | 3 | 5 | 3 + 16 = 19 | 3 + 16 = 19

 答案是`20`。 

这表明重复相同的要求力间距`k`有效的任务之间。

 ## 边缘情况

 当所有元素都可以被整除时`k`，每个余数都为零，并且频率图保持为空。 该算法在不进入调度阶段的情况下正确输出零。 

当只有一个元素具有非零余数时，答案变为`d + 1`， 自从`f = 1`消除了间距项。 这证实了分组逻辑没有引入人为延迟。 

当许多元素共享相同的赤字时，该公式会强制时间线性增长，匹配相同需求竞争连续可用时间戳的约束`k`。
