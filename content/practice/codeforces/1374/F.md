 ## 解决方案
 ## 问题理解

 我们得到一个数组和一个非常具体的原始操作：我们可以选择任何位置并将三个连续元素的块向右旋转。 这意味着本地三元组`[x, y, z]`变成`[z, x, y]`。 多次重复这个操作，我们想要将数组转换为非降序，或者决定无法完成。 

关键在于该操作是极其本地化的，但不像交换那样对称。 它的行为就像一个受约束的排列生成器：它只能以受控的循环模式向左移动元素。 我们被允许最多约`n^2`每个测试用例的操作，以及总和`n`很小，所以`O(n^3)`风格模拟仍然处于边缘但结构化`O(n^2)`预计施工。 

一个微妙的问题是此操作不允许任意交换。 例如，如果我们尝试交换两个相邻元素，则无法直接执行。 我们只能使用三元组“冒泡”元素，并且排列的奇偶性变得相关。 这是不可能的第一个根源：并非每个排列都是可达的。 

另一个不明显的边缘情况是存在重复项时。 由于值并不明确，因此我们必须小心，不要仅仅依赖排列奇偶性； 相反，我们必须确保我们可以构造排序的多重集排列。 

当反转“卡在”靠近阵列末端的距离 1 处时，会出现第二种边缘情况。 例如，在长度为 3 的数组中，只能进行循环旋转，因此只存在三种排列，而不是全部 6 种。这立即表明操作空间受到限制。 

试图贪婪地冒泡最小元素而不跟踪奇偶性或可行性的幼稚方法可能会失败。 例如，关于`[3, 1, 2]`，粗心的基于交换的直觉可能会假设我们可以对大小为 3 的任何内容进行排序，但只存在循环旋转，并且我们无法达到`[1,2,3]`从`[3,1,2]`因为这需要非循环排列奇偶校验变化。 

## 方法

 一个蛮力的想法是使用局部改进来模拟排序：反复查找不在正确位置的最小元素，并尝试使用三重旋转操作将其向左移动。 这类似于冒泡排序，但移动受到限制。 

在实践中，这很快就会变得不清楚，因为将元素向左移动一个位置是不可能直接实现的。 相反，我们需要使用一系列三重旋转来有效地执行受控的位置交换`i`和`i+1`使用第三个元素。 每次这样的交换都会花费固定数量的操作，但盲目地实施会导致结构不佳，并且可能会超出`n^2`如果不仔细组织，就会受到束缚。 

关键的见解是从左到右修复数组。 在位置`i`，我们根据排序顺序决定必须将哪个元素放置在那里，然后使用三重旋转将该元素移到左边。 操作`[a_i, a_{i+1}, a_{i+2}] -> [a_{i+2}, a_i, a_{i+1}]`允许我们通过以受控方式将元素与其前面的两个元素交换来有效地向左旋转元素。 通过重复应用这个，我们可以模拟将目标元素逐步移向正确的位置。 

然而，存在一个结构限制：每个操作都将排列的奇偶性保留到已知的不变量，因此，如果在贪婪地放置元素后我们最终得到一个无法通过长度为 3 的旋转来修复的最终后缀，我们必须拒绝。 这减少了对最后两个元素的最终检查：如果尚未实现排序，我们将验证是否可以使用允许的旋转来解析剩余的配置。 实际上，这会导致标准条件：如果最后我们在只需要 2 长度交换的位置上出现不匹配，则答案是不可能的。 

有效的结构是从左到右的贪婪放置与重复的局部旋转相结合，以将正确的元素冒泡到位`i`。

 | --- | --- | --- | --- |
 | 无结构的蛮力冒泡 | O(n^3) | O(n^3) | O(n) | 太慢/不稳定|
 | 贪婪从左到右三次旋转 | O(n^2) | O(n^2) | O(n) | 已接受 |

 ## 算法演练

 我们维护数组并逐步构建排序顺序。 

1. 计算数组的排序版本。 这是我们的目标配置，定义了每个位置必须包含的内容。 
2. 从左到右迭代位置，停在`n - 2`。 在每个位置`i`，找到索引`j`其中位置的正确值`i`目前居住。 
3.如果`j < i`，有些东西不一致，因为早期的位置已经固定了。 如果我们保持正确性，这种情况就不会发生。 
4. 如果`j > i`，我们将元素移动到`j`向左直至到达位置`i`。 每个步骤在位置处使用三次旋转`k = j - 2`，它将目标元素向左移动一步，同时保留相对顺序约束。 
5. 每次旋转后，我们递减`j`1 或 2 取决于局部结构，但实际上我们正在将其距离缩小到`i`。 
6. 一旦元素被放置在位置`i`，我们继续`i + 1`。 
7. 处理后最多`n - 2`，我们检查数组是否完全排序。 如果不是，我们尝试使用最多两次最终旋转来解析最后一个小后缀； 如果不可能，我们输出`-1`。 

### 为什么它有效

 不变的是完成位置后`i`, 前缀`[0 .. i]`是固定的并且匹配已排序的数组。 三重旋转永远不会将元素移动到窗口之外`[k, k+2]`，所以一旦一个元素被放置在位置`i`，以后的操作不再打扰它。 这保证了单调进度。 因为每个放错位置的元素最多都会被拉到左边`n`位置和每次移动成本恒定的操作，总操作受`O(n^2)`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    ops = []
    
    b = sorted(a)
    
    for i in range(n - 2):
        # find target position
        j = i
        while j < n and a[j] != b[i]:
            j += 1
        
        while j - i >= 2:
            # apply rotation at j-2
            k = j - 2
            a[k], a[k+1], a[k+2] = a[k+2], a[k], a[k+1]
            ops.append(k + 1)
            j -= 2
        
        if j == i:
            continue
        
        # final adjustment if distance is 1
        if j == i + 1:
            # need to use a temporary rotation to resolve
            if i + 2 >= n:
                print(-1)
                return
            k = i
            a[k], a[k+1], a[k+2] = a[k+2], a[k], a[k+1]
            ops.append(k + 1)
            j = i
        
    if a != b:
        print(-1)
        return
    
    print(len(ops))
    print(*ops)

t = int(input())
for _ in range(t):
    solve()
```核心结构是贪婪对齐循环。 重要的实现细节是元素如何向左移动：每个操作都作用于`(j-2, j-1, j)`使目标距离前方两步。 这避免了尝试直接模拟非法相邻交换。 

最后检查`a != b`这是至关重要的，因为贪婪过程可能会留下局部看起来固定但全局未排序的配置，特别是在最后两个位置附近。 

必须注意索引：每个操作都根据需要存储在基于 1 的索引中，并且循环避免访问越界三元组。

 ## 边缘情况

 临界边缘情况是当正确的元素已经在其目标位置的距离 1 内但无法放置时，因为没有有效的三重窗口终止于该位置。 例如，当`i = n - 2`，如果元素位于`n - 1`，因为没有有效的`(i, i+1, i+2)`存在。 该算法通过要求明确地检测到这一点`i + 2 < n`在最终调整之前，确保我们不会尝试无效操作。 

另一个边缘情况是重复值。 当存在重复项时，匹配步骤必须确保我们选择正确的出现项； 否则，我们可能会将某个元素拉得太远并干扰正确性。 贪心方法始终使用未排序后缀中最左边的有效出现，从而保持与目标多重集结构的一致性。
