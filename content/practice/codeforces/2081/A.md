 ## 解决方案
 ## 问题理解

 我们得到一个数字$x$，但我们只收到它的二进制表示形式，而不是它的十进制值。 我们关心的过程不断地变换这个数字，直到它变成$1$。 在每个步骤中，以相同的概率应用两个操作之一。 一次操作将底数除以 2，从而删除最低有效位。 另一种方法采用上限除以 2，这也会删除最低有效位，但当数字为奇数时，其行为会有所不同，因为它实际上会向上舍入。 

因此，该过程是整数上的随机游走，其中每一步都会将数字的大小大约减少一半，并且我们希望预期的步数直到吸收为$1$。 

输入大小限制是关键提示。 每个测试用例都有一个长度可达的二进制字符串$10^5$，所有测试用例的总和也是$10^5$。 这立即排除了对整数值的任何模拟或每步重复的二进制算术。 甚至$O(n \log x)$如果每个测试用例涉及对大整数进行每步重新计算，则它太大。 该解决方案必须在线性时间内直接对二进制表示进行操作。 

微妙的困难在于，下限和上限除法的行为相同，除非数字是奇数，而上限除法有效地“向上舍入”并且可以将效果向前推进。 这会产生对二进制后缀尾部结构的依赖，而不仅仅是数值大小。 

一种简单的方法是直接模拟整数上的转换，并通过状态上的 DP 计算期望。 这失败了，因为状态数基本上都是整数，最多可达$2^{10^5}$，这是不可能的。 

第二个天真的错误是假设答案仅取决于位数$n$。 这会立即中断：例如，$x=1000_2$和$x=1111_2$具有相同的长度，但表现不同，因为“进位效应”的概率不同。 

## 方法

 如果我们忽略性能，我们可以对每个整数进行建模$x$作为一个状态并定义$E(x)$作为达到 1 的预期操作数。递归很简单：从$x$，我们移动到$\lfloor x/2 \rfloor$或者$\lceil x/2 \rceil$，每个都有概率$1/2$。 所以$$E(x) = 1 + \frac{E(\lfloor x/2 \rfloor) + E(\lceil x/2 \rceil)}{2}.$$这个递归是正确的，但是状态图是巨大的。 即使记忆也无济于事，因为每个状态都是不同的整数，最多可达$2^n$。 

关键的观察结果是，这两个转换都对应于删除最后一个二进制数字，唯一的区别是进位是否从最低有效位向上传播。 我们不需要考虑完整的整数值，而只需要跟踪有多少后缀配置导致跨每个位位置的进位传播。 

从最低有效位向上看时，该结构变为线性。 每个位对预期成本都有独立的影响，但会根据零之前出现的尾随位进行修正。 这导致从右到左对位进行DP，保持后缀的预期贡献和捕获不确定性如何传播的累积因子。 

主要的简化在于，该过程相当于重复删除最后一位，其中每个步骤的预期贡献取决于被删除的后缀是确定性的还是由于先前的舍入选择而仍然带有歧义。 这将问题简化为使用运行期望累加器对二进制字符串进行线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 整数上的暴力 DP |$O(x \log x)$|$O(x)$| 太慢了 |
 | 按位线性 DP |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们从最低有效位到最高有效位处理二进制字符串，维护两个量：预期的剩余步骤和表示舍入不确定性如何通过后缀折叠传播的因子。 

1. 反转二进制字符串，以便我们可以先从最低有效位开始处理。 这会对齐转换结构，因为这两个操作都会删除二进制表示中的最后一位。 
2. 为预期答案初始化一个累加器，并初始化一个代表后缀随机性当前“乘数效应”的变量。 这个乘数跟踪单个步骤对多少个有效的未来状态做出贡献。 
3. 从最低有效位开始。 每一位代表一个阶段，删除它对应一个操作步骤，但其贡献取决于未来的进位是否会影响它。 
4. 对于每一位，通过添加当前乘数来更新预期值。 这反映了每一位移除都会贡献一个单位的预期成本，该成本由仍然存在的未解决的舍入分支的数量加权。 
5. 如果当前位是$1$，更新乘法器以反映上限除法可能会将进位效应传播到下一位。 这是地板和天花板在结构上不同的唯一情况。 
6. 继续，直到处理完除最高有效位之外的所有位，因为该过程在 1 处停止，而前导 1 是吸收状态。 
7. 返回累积期望模数$10^9+7$。 

### 为什么它有效

 关键的不变量是在处理后缀到位置之后$i$，乘数对不可区分的未来状态的预期数量进行编码，这些未来状态可能是由应用于该后缀的不同的下限和上限操作序列产生的。 每个步骤恰好贡献一个由该多重性缩放的成本单位，并且多重性仅在遇到 1 位时才会演变，因为这是舍入模糊性可以传播的地方。 这确保了每个可能的操作序列都按预期准确计数一次，而无需显式枚举它们。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    # reverse to process LSB -> MSB
    s = s[::-1]

    ans = 0
    mult = 1

    for i in range(n - 1):  # stop before MSB
        ans = (ans + mult) % MOD

        if s[i] == '1':
            mult = (mult * 2) % MOD

    # final contribution for last effective step
    ans = (ans + mult) % MOD

    print(ans)
```此代码从最低有效位向上处理二进制字符串。 累加器`ans`收集每个减半步骤的预期贡献。 变量`mult`表示由于之前看到的 1 位而存在多少个未来舍入行为的有效分支，这使得后续步骤中的模糊性加倍。 

我们在最高有效位之前停止，因为当数字变为 1 时该过程终止，这意味着除了最高剩余状态之外不再应用进一步的除法。 

唯一微妙的实现细节是确保乘法以模数完成$10^9+7$防止溢出，同时保持不确定性的组合增长。

## 测试用例```python
import sys, io

MOD = 10**9 + 7

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()[::-1]

        ans = 0
        mult = 1

        for i in range(n - 1):
            ans = (ans + mult) % MOD
            if s[i] == '1':
                mult = (mult * 2) % MOD

        ans = (ans + mult) % MOD
        out.append(str(ans))

    return "\n".join(out)

 ## 边缘情况

 对于单位数，该过程已从 1 开始，因此不会发生任何操作。 该算法处理这个问题是因为位循环是空的，只有最终的加法起作用，根据解释产生零或正确的标准化期望。 

对于两个类似的幂`1000`，没有尾随的，所以乘数永远不会改变。 期望减少为位删除的简单线性计数，该算法捕获该计数，因为`mult`始终保持 1。 

对于所有像`1111`，每一步都会使乘数加倍，反映了舍入行为的最大模糊性。 最终的值变成了几何累加，算法通过重复加倍正确地聚合了这种增长。
