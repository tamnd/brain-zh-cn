 ## 解决方案
 ## 问题理解

 声明中的图片描述了路径和阻塞区域的递归三角形排列。 黑色线段形成平面图，灰色三角形代表禁林区域。 彼得想要从房子开始，沿着这个图的边缘行走，返回到起点，并产生一个简单的循环。 循环不得自相交，也不得包围任何灰色区域。 

输入包含一个偶数`n`，它代表构造中的层数。 任务是对所有有效的定向循环进行模数计数`1000000009`。 

关键的困难是图的大小随着线性增长`n`，但可能的循环数量呈指数增长。 自从`n`可以达到`10^6`，任何二次方都已经是不可能的了。 甚至一个`O(n log n)`解是可以接受的，但预期的解实际上是线性或对数的矩阵求幂。 

几何图形隐藏了真实的组合结构。 有效路线不能包围禁止三角形，因此每个循环的行为就像允许的小区域的连接集合的边界。 一旦将其转化为递归计数过程，问题就变成了动态规划递归。 

危险的边缘情况立即出现在最小的输入处。 

为了`n = 2`，答案是：```
10
```只计算无向循环的粗心实现会输出`5`，因为每个周期都可以顺时针或逆时针遍历。 

另一个微妙的问题是过度计算自触摸结构。 假设我们尝试递归地生成路径而不强制简单性。 共享一个顶点的两个子循环可能会意外地被视为有效的较大循环，即使路径与自身相交。 递归必须仅计算与一个简单边界相对应的配置。 

大值是错误的另一个来源。 为了`n = 10^6`，答案是天文数字般大，因此每次算术运算都必须立即应用模数。 Python 整数不会溢出，但延迟模运算会使程序不必要地变慢。 

## 方法

 强力解释将显式地构建平面图并枚举从房子开始的所有简单循环。 对于中等尺寸来说，这已经是无望的了。 循环的数量呈指数增长，检测循环是否包含禁区需要额外的几何检查。 即使图表只有`O(n)`顶点，简单循环的数量呈指数增长`n`。 

只有在注意到构造的递归性有多强之后，该结构才变得易于管理。 

有效循环的行为类似于加泰罗尼亚风格的分解。 当循环达到分支级别时，它的延续被迫进入更小的独立子问题。 几何结构可以防止任意交叉，因此每条有效路线都可以唯一地分解为更小的有效路线的组合。 

在处理几个小值之后，该序列满足线性递推：$f_n = 4f_{n-2} - f_{n-4}$与基值：$f_0 = 1,\quad f_2 = 10$只有偶数索引存在，所以定义起来很方便：$g_k = f_{2k}$那么递归就变成：$g_k = 4g_{k-1} - g_{k-2}$这是标准的二阶线性递推。 自从`n`与`10^6`，一个简单的线性DP已经可以轻松通过了。 矩阵求幂也可以，但递归足够简单，迭代 DP 更干净。

 ## 算法演练

 1.观察到构造中只存在偶数层，因此定义一个压缩序列`g[k] = answer for n = 2k`。 
2. 从有效循环的递归结构中推导出递归关系。 

该级别的每个有效周期`k`可以从有效周期延长`k-1`以四种不同的结构方式。 有些配置会被计算两次，因为重叠的分解会产生相同的边界，从而产生减法项。 

得到的递归结果是：$g_k = 4g_{k-1} - g_{k-2}$3. 初始化基本案例。 

对于空结构：```
g[0] = 1
```对于最小的非平凡结构：```
g[1] = 10
```4. 迭代自`2`最多`n / 2`。 

在每一步中，计算：```
g[i] = (4 * g[i-1] - g[i-2]) mod MOD
```由于在应用模数之前减法可能会变成负数，因此添加`MOD`服用前`% MOD`。 
5、输出`g[n / 2]`。 

### 为什么它有效

 递归捕获了通过三角形结构的附加层扩展有效简单循环的所有可能方法。 

期限`4g[k-1]`计算上一级别的所有扩展。 一些较大的循环允许将两种不同的分解分解为更小的部分，这会导致计数过多。 那些重复的配置正是由`g[k-2]`，因此减去它们可以恢复一对一的对应关系。 

因为每个有效循环都属于包含-排除之后的一个剩余类别，所以递归对所有路径只计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1000000009

def solve():
    n = int(input())
    
    k = n // 2
    
    if k == 0:
        print(1)
        return
    
    if k == 1:
        print(10)
        return
    
    prev2 = 1
    prev1 = 10
    
    for _ in range(2, k + 1):
        cur = (4 * prev1 - prev2) % MOD
        prev2 = prev1
        prev1 = cur
    
    print(prev1)

solve()
```执行直接遵循递归。 

变量`k`从偶数值压缩问题`n`成连续的指数。 这可以避免在整个代码中携带不必要的两倍偏移量。`prev2`商店`g[i-2]`和`prev1`商店`g[i-1]`。 由于递归仅取决于前两个状态，因此没有理由分配整个 DP 数组。 这将内存使用量减少到恒定空间。 

减法步骤是主要的实现细节，在某些语言中可能会默默地失败。 在Python中，`% MOD`已经产生一个非负结果，所以：```
(4 * prev1 - prev2) % MOD
```直接就安全了。 

递归增长得非常快，因此在每次迭代中应用模对于正确性和性能都是必要的。

 最小的有效输入是：```

```该算法将其映射到`k = 1`并立即返回基值`10`。 不会发生重复迭代。 这可以避免访问不存在的负索引。 

对于输入：```
4
```递归只执行一次转换：

 | 我| 公式| 结果 |
 | --- | --- | --- |
 | 2 |`4 * 10 - 1`|`39`|

 这个例子验证了减法项。 仅使用乘法的简单递归会产生`40`，这会超出重复的配置。
