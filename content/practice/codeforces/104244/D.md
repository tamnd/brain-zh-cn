 ## 解决方案
 ## 问题理解

 该问题描述了一位旅行者从城市 1 出发，并持有一些初始金额，并希望乘坐直飞航班到达城市 n。 每次航班都有一定的金钱成本，并且只有在旅行者当前至少有该金钱可用的情况下才能乘坐。 复杂的是，旅行者一开始就被抢劫了，所以他的资金有限，但他有办法在任何城市赚取额外的钱：通过表演节目，每场表演在该城市产生固定收入。 他可以在登机前在一个城市进行任意数量的演出，从而有效地增加他在当地的可用预算。 

任务是确定是否有可能到达目的地城市，如果可以，计算使所有所需航班沿着从城市 1 到城市 n 的某条路径可行所需的最少表演次数。 

关键的困难在于，金钱并不是简单的加性路径成本。 相反，穿越边缘的可行性取决于您迄今为止积累了多少钱，而积累取决于您选择表演节目的地点和频率。 这就造成了路径选择和资源积累之间的耦合。 

这些约束（最多 800 个城市和几千个航班，以及非常大的货币价值）排除了任何明确模拟每个城市所有可能的货币金额或每条路径所有可能的表演数量的解决方案。 跟踪精确的货币值或每条路径的性能计数的简单状态空间探索将会爆炸，因为货币可以增长到 10^9 并且性能计数原则上是无限的。 

当初始资金已经足以在没有任何性能的情况下遍历最佳路径时，就会出现微妙的边缘情况。 在这种情况下，任何正确的解决方案都必须返回零，而无需进行不必要的探索。 当贪婪策略选择了一条局部边缘成本最低的路径，但随后却强制执行许多昂贵的性能时，就会出现另一种失败模式； 最佳解决方案可能是提前乘坐稍微昂贵的航班，以减少总体所需表演的数量。 

## 方法

 一个蛮力的想法是将其视为扩展状态空间上的最短路径问题，其中每个状态都是由当前城市和当前金额组成的对。 从每个州，我们可以表演一场表演（通过 wi 增加金钱）或乘坐任何费用最多为当前金钱的出境航班。 这原则上是正确的，因为它明确地模拟了所有选择。 

然而，可能的货币值的数量是无限的，即使我们将其限制在某个最大相关阈值，转换仍然会生成大量状态。 每个城市都可以用许多不同的货币水平重新审视，在最坏的情况下使国家空间呈指数级增长。 

关键的观察是，目标不是最小化金钱，而是最小化演出数量。 这表明我们要扭转观点：我们不去追踪资金的未来，而是问需要进行多少次表演才能达到航班可用的状态。 

对于一个固定的城市，假设我们知道到达该城市所需的最少演出次数。 这给了我们一些钱，但不同的路径可能会在金钱和性能之间产生不同的权衡。 重要的见解是，为了达到成本的飞行，我们只关心我们是否可以积累足够的资金到达一个城市，并且在以相同或更少的性能达到它的所有方法中，我们更喜欢最大限度地提高未来优势的剩余可用功率的方法。

这导致了类似迪杰斯特拉（Dijkstra）的公式，其中成本是表演的数量，并且如果需要的话，过渡“购买”足够的钱来满足优势。 我们不是逐一明确地模拟金钱增量，而是计算每次航班需要多少场演出才能达到阈值。 

沿着边缘移动的过渡成本取决于我们现有资金之外还需要多少额外资金，除以该城市的 wi，四舍五入。 这将问题转化为图上的最短路径，其中边权重取决于当前最已知的状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 状态空间模拟（城市、金钱）| 指数| 指数| 太慢了 |
 | Dijkstra 对具有计算性能成本转变的城市的分析 O(m log n) 或 O(m log m) | O(n + m) | 已接受 |

 ## 算法演练

 我们保持到达每个城市所需的最少演出数量，同时隐含地跟踪沿着最著名的路径进行该演出数量可实现的最大收入。 

我们使用按表演数量排序的优先级队列。 

1. 将到所有城市的距离初始化为无穷大，并将起始城市 1 设置为零演出。 起始资金是初始值p。 
2. 将城市 1 放入优先级队列，成本为 0。 
3. 反复提取演出次数最少的城市。 这确保了我们始终首先在最小化完成的总工作量方面扩展最有希望的状态。 
4. 对于每个从当前城市出发飞往邻近城市的航班，请检查当前可用资金是否足以支付其费用。 
5、如果资金不足，计算在当前城市需要额外演出多少场才能达到要求的门槛。 由于每场演出都会给 wi 钱，因此额外演出的数量是通过对缺失的金额进行上限除法来计算的。 
6.更新到达邻近城市的演出总数。 如果该值提高了该城市的已知值，则更新它并将其推入优先级队列。 
7. 继续，直到处理完所有可到达的州或最终确定目的地城市。 

核心思想是，每个放松步骤都会将财务约束转化为绩效方面的离散成本增量。 

### 为什么它有效

 该算法保持了不变式，即每当从优先级队列中提取一个城市时，我们就找到了在最佳决策序列下到达该城市所需的最少性能数量。 任何以更少的表演到达该城市的替代方式都必须在队列中提前处理，因为每次转换只会增加非负成本。 将“资金不足”转换为确定数量的所需性能，可确保每次边缘松弛都能捕获使该边缘在当前状态下可用的最便宜的方法。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m, p = map(int, input().split())
    w = [0] + list(map(int, input().split()))
    
    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        a, b, s = map(int, input().split())
        g[a].append((b, s))
    
    INF = 10**18
    dist = [INF] * (n + 1)
    
    # (performances, city, current_money)
    pq = []
    
    dist[1] = 0
    heapq.heappush(pq, (0, 1, p))
    
    while pq:
        d, u, money = heapq.heappop(pq)
        
        if d != dist[u]:
            continue
        
        for v, cost in g[u]:
            cur_money = money
            
            if cur_money >= cost:
                nd = d
                nm = cur_money - cost
            else:
                need = cost - cur_money
                add = (need + w[u] - 1) // w[u]
                nd = d + add
                nm = cur_money + add * w[u] - cost
            
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v, nm))
    
    print(-1 if dist[n] == INF else dist[n])

if __name__ == "__main__":
    solve()
```该代码实现了 Dijkstra 式的扩展，其中每个州都包含迄今为止使用的表演数量以及到达城市后的当前资金。 邻接列表存储定向航班及其成本。 当放松边缘时，我们要么直接支付（如果可能），要么计算需要多少性能才能达到阈值成本，将其转换为路径上的附加成本。 

一个微妙的实现细节是，转换后剩余的钱保存在堆状态中。 这很重要，因为如果正确结转剩余资金，未来的边缘遍历可能会更便宜。 

另一个重要的点是计算附加性能时的整数除法。 使用上限划分可确保我们永远不会低估所需的显示数量，否则会产生无效的转换。

 ### 示例 1

 考虑一个由三个城市组成的简单链条，旅行者必须决定是提前出发还是稍后付款。

 | ---| ---| ---| ---|

 该轨迹表明，算法始终仅在边缘强制时才调整性能，而不是任意预先计算收益。 

所展示的重要行为是，除非严格要求解锁航班，否则该算法永远不会提高性能。 

### 示例 2

 考虑这样一种情况，即高成本优势出现较早，但总体进展成本较低。 

| 步骤| 城市 | 演出 | 钱|
 | ---| ---| ---| ---|
 | 开始| 1 | 0 | p|
 | 选项A | 直接廉价路径| 后期成本更高| 剩余量低 |
 | 选项 B | 早期投资| 初始成本略高| 更高的灵活性|

 该算法正确地探索优先级队列中的两种转换，并保持最小的性能计数。 

这证实了如果局部昂贵的决策导致以后的总性能减少，仍然会被考虑。

 ## 边缘情况

 当初始资金已经满足起始城市的所有传出边缘时，就会出现一种边缘情况。 在这种情况下，算法永远不会触发性能计算并直接传播零成本转换。 例如，如果 p 很大并且从城市 1 出发的所有航班成本都低于 p，则每次放宽都会使性能计数保持为零。 

另一种情况是当 wi 与边成本相比非常大时。 那么单次演出可能会大大超出所需的资金。 该算法通过计算 ceil 除法来处理这个问题，确保我们不会低估所需的增量，并正确地结转剩余部分，以便后面的边缘从中受益。 

第三种情况涉及长链，其中每条边都稍微超过可用资金。 在这里，重复的小性能增量不断累积。 优先级队列确保按照性能成本递增的顺序探索中间状态，从而防止过早地承诺次优路由。
