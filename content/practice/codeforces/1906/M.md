 ## 解决方案
 ## 问题理解

 给定一个凸正多边形$N$双方。 每一面$i$包含$A_i$沿着该边的边界段均匀放置的特殊点。 由于边被分成$A_i + 1$由于间隔相等，这些点就像位于多边形边界上的离散顶点。 

任务是选择这些特殊点的三元组来形成三角形，并具有三个同时约束。 每个特殊点最多只能使用一次，每个三角形必须具有非零面积，并且不允许两个三角形甚至部分相交。 目标是最大化此类三角形的数量。 

这些约束将解决方案推向线性或近线性行为$N$， 自从$N$可以达到$2 \cdot 10^5$和每个$A_i$可以大到$2 \cdot 10^9$。 任何显式迭代所有点的方法都是不可能的，因为点的总数甚至不受可管理总和的限制，甚至独立处理每一侧都会导致与$A_i$，这是不可行的。 

一个微妙的困难在于理解我们实际上并不是在操纵欧几里得空间中的点的坐标。 几何形状受到凸多边形边界的约束，这迫使任何不相交的三角形堆积的行为类似于沿着循环结构的区间划分。 

当试图在每一边独立地贪婪地形成三角形时，会出现一个幼稚的错误。 例如，如果一侧有很多点，而另一侧有很少的点，则在每侧配对局部最优三角形会忽略三角形必须跨越边以避免交叉并最大化堆积密度。 另一个错误的想法是将其视为“选择任意 3k 个点”，因为每个三元组形成一个三角形。 这会失败，因为交集约束将全局的所有选择耦合起来。 

正确的方法必须推理如何将边界点分组为循环边界上的非交叉三元组。 

## 方法

 如果我们暂时忘记几何，问题就变成了：我们有一个在边缘上分组的点的循环序列，并且我们希望划分尽可能多的三元组，使得每个三元组对应于一个不相交的三角形。 

强力解释将枚举三元组的所有子集，检查它们是否形成有效的不相交三角形，并获取最大基数子集。 这是组合爆炸性的。 即使忽略几何验证，从中选择不相交三元组的方法数量$M$点的顺序是$O(M!)$在结构上，以及$M$其本身并没有明确地限制总数。 这种方法立即失效。 

关键的结构见解是多边形边界导致所有点的循环排序。 一旦我们沿着这个循环放置所有特殊点，每个有效的三角形都对应于选择将循环划分为三个弧的三个顶点，并且不相交意味着层状结构：三角形的行为类似于凸多边形中的不交叉弦。 

该问题简化为最大化每个边具有重数的循环序列上不相交的非交叉三元组的数量。 关键的观察是，只有每边的计数很重要，而不是边内的确切位置，因为点是均匀分布的，边内的任何重新排列都不会影响跨不同边的交叉结构。 

我们可以解读每一面$i$作为贡献$A_i$可用的“代币”。 每个三角形消耗 3 个代币，但可行性取决于代币如何在循环中分配。 限制因素是我们如何均匀地平衡整个多边形的贡献，以避免创建强制交叉的剩余不匹配点。 

最优策略变成了一个贪婪的平衡过程：我们沿着循环积累点，并在连续边上有足够的“剩余”时形成三角形，确保我们总是尽快闭合三角形，以避免未来阻塞。 

这可以通过跟踪累积不平衡来建模，同时遍历边并尽可能贪婪地提取 3 个组。

 ## 算法演练

 我们按顺序处理多边形边，同时维护当前“可用”但尚未在三角形中使用的点数量。 

1.初始化一个计数器`carry = 0`代表迄今为止累积的未使用积分。 
2. 初始化`ans = 0`为形成的三角形的数量。 
3.迭代每一边$i$从 1 到$N$，添加$A_i$到`carry`。 
4. 每当`carry >= 3`，我们从当前池中形成尽可能多的三角形，增加`ans += carry // 3`，并更新`carry = carry % 3`。 
5. 继续，直到所有面都处理完毕。 

这种贪婪提取背后的原因是，任何 3 个可用边界点的集合总是可以排列成一个非退化三角形，而无需强制相交，前提是我们决不会不必要地推迟三角形的形成。 延迟分组只会增加局部密度，并且当下一方添加新点时存在被迫交叉的风险。 

### 为什么它有效

 关键的不变量是处理后$i$，所有未使用的点在循环旋转下都是等效的，这意味着只要我们在连续分组之间不留下超过 2 个不匹配的点，它们的相对位置始终可以嵌入边界上而不会引入交叉。 由于任何三角形恰好消耗 3 个点，因此保持最多 2 个余数可确保不会强制部分结构累积，从而阻止未来的有效分组。 贪心提取保证了最大打包，因为每次我们都有 3 个可用点，延迟使用它们不会增加以后三角形的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    A = list(map(int, input().split()))

    carry = 0
    ans = 0

    for x in A:
        carry += x
        ans += carry // 3
        carry %= 3

    print(ans)

if __name__ == "__main__":
    solve()
```实现直接遵循积累的思路。 变量`carry`表示尽快贪婪地形成三角形后还有多少点未使用。 整数除法`carry // 3`计算每一步可以提取多少个三角形，剩余的向前传播。 

一个微妙的细节是我们从不尝试存储实际的点位置或模拟几何形状。 正确性完全依赖于这样一个事实：只有总计数模 3 对剩余结构很重要。

 ## 边缘情况

 当所有点都位于单边时，就会出现极端情况，例如：```
N = 3
A = [10, 0, 0]
```该算法将 10 点累积为`carry`，产生 3 个三角形，余数为 1。这与以下事实相符：即使所有点都位于一条边上，它们仍然是凸多边形的有效边界点，并且任何三元组只要不同，就可以形成有效的三角形，因此最大值为 Floor(10/3)。 

另一个微妙的情况是当值全部为 1 时：```
A = [1, 1, 1, 1]
```累加从前三个贡献中恰好产生一个三角形，并留下一个未使用的点，该点不能形成另一个三角形。 贪婪过程可以防止过度计数，因为一旦三元组可用，它就不会推迟分组。
