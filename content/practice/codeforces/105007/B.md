 ## 解决方案
 ## 问题理解

 我们得到了一个由一系列高程描述的一维地形。 每个索引代表路径上的一个位置，并且每个位置都有一个高度值。 对于任意两个查询位置$i$和$j$，我们必须在特定的障碍规则下判断它们之间是否存在直线视线。 

该规则规定，之间的段$i$和$j$如果存在任何中间位置，其标高至少与两个端点中较高的一个一样高，则遮挡可见性。 换句话说，如果我们定义$H = \max(e_i, e_j)$，那么每个索引严格介于$i$和$j$标高必须严格小于$H$使两个端点可见。 

每个查询都是独立的。 我们不会更新地形，只是反复检查能见度条件。 

约束允许最多$N = 100{,}000$职位，但仅限于$q = 100$查询。 这种不平衡是关键的结构性暗示。 任何积极预处理或每个查询花费对数工作的解决方案都是可以接受的，而每个查询的任何线性工作仍然可以轻松通过，因为$100 \times 100{,}000 = 10^7$Python 中的操作是安全的。 

预处理时排除了对所有位置对的二次扫描，但每个查询沿单个段扫描仍然可行。 

当出现一种微妙的情况时$i = j$。 在这种情况下，没有中间点，因此可见性应该始终为真。 

另一个极端情况是端点之间的最大高程不唯一。 例如，如果两个端点相等并且某个内部点与相同高度匹配，则可见性一定会失败，因为条件允许“大于或等于”，而不是严格大于。 仅检查严格更大的内部值的简单解决方案将错误地接受这种情况。 

## 方法

 暴力方法通过严格扫描每个查询之间的每个索引来独立评估每个查询$i$和$j$。 对于固定查询，我们计算$H = \max(e_i, e_j)$然后检查任意中间位置是否有至少标高$H$。 如果存在这样的立场，答案是“否”，否则是“是”。 

这种方法是正确的，因为它直接实现了可见性的定义。 问题是成本。 在最坏的情况下，单个查询几乎跨越整个数组，因此每个查询都会花费$O(N)$。 如果查询最多 100 个，则总成本变为$O(Nq) = 10^7$，这是边界，但在 Python 中对于紧密循环来说仍然可以接受，但几乎没有留下开销余地。 

通过认识到问题的结构不需要预处理或高级数据结构，我们可以避免不必要的开销。 数组是静态的，并且查询是独立的，因此每个查询最简单的线性扫描已经是给定约束的最佳选择。 

不需要线段树或RMQ结构，因为查询很少。 主要优化是概念性的：避免过度设计并直接实现条件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的强力扫描 |$O(Nq)$|$O(1)$| 已接受 |
 | 线段树/RMQ |$O((N+q)\log N)$|$O(N)$| 已接受但没有必要 |

 ## 算法演练

 1. 对于每个查询$(i, j)$，标准化间隔，以便我们始终从左到右迭代。 这避免了扫描内部的条件分支并简化了中间索引的推理。 
2. 计算$H = \max(e_i, e_j)$。 该值表示任何阻挡点必须达到或超过的可见性阈值。 
3. 严格迭代所有索引$i$和$j$。 对于每个位置$k$，检查是否$e_k \ge H$。 如果满足这个条件，视线就会被阻挡，答案立即是“否”。 
4. 如果扫描完成后没有发现任何阻挡位置，则该间隔满足可见性规则，因此答案为“是”。 

关键的决策点是扫描期间提前退出。 一旦发现阻塞高度，继续扫描对正确性没有影响，只会浪费时间。 

### 为什么它有效

 对于任何一对端点，可见性完全取决于内部最大值是否达到阈值$H = \max(e_i, e_j)$。 该算法在整个内点集上精确检查此条件。 由于每个可能的障碍物都必须出现在该集合中，并且每个检测到的障碍物都会正确地使可见性失效，因此该决策等同于正式定义。 除了这个最大检查之外，没有任何中间配置或全局属性重要。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    e = list(map(int, input().split()))

    for _ in range(q):
        i, j = map(int, input().split())
        i -= 1
        j -= 1

        if i == j:
            print("yes")
            continue

        if i > j:
            i, j = j, i

        H = e[i] if e[i] > e[j] else e[j]

        ok = True
        for k in range(i + 1, j):
            if e[k] >= H:
                ok = False
                break

        print("yes" if ok else "no")

if __name__ == "__main__":
    solve()
```该解决方案读取数组一次并独立回答每个查询。 每个查询都会标准化端点，以便扫描方向保持一致。 门槛$H$直接根据端点值计算，并且循环仅检查内部索引。 当阻塞峰较早出现时，早期中断对于避免不必要的扫描至关重要。 

必须小心索引，因为输入是从 1 开始的，但 Python 数组是从 0 开始的。 平等案例$i = j$显式处理以避免空循环歧义。 

## 工作示例

 ### 示例 1

 输入：```
5 2
1 3 2 4 1
1 4
2 5
```对于查询 (1, 4)，端点是 1 和 4，所以$H = 4$。 我们检查位置 2 和 3。它们的值为 3 和 2，均低于 4，因此可见性成立。 

对于查询 (2, 5)，端点为 3 和 1，因此$H = 3$。 我们检查位置 3 和 4，即 2 和 4。由于 4 至少为 3，因此可见性失败。 

| 查询 | 我| j | 哈 | 内部价值观| 封锁？ | 结果 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 4 | 4 | 3, 2 | 没有 | 是的 |

 这证实了该算法正确区分了干净的下降和阻挡视线的中间峰值。 

### 示例 2

 输入：```

1 4
```这里$H = 5$，每个内部值为5，立即满足阻塞条件。 该算法找到第一个内部索引并拒绝查询。 

| k | e[k] | 与H=5比较| 状态 |

 | 2 | 5 | ≥ | 块|

 ## 边缘情况

 临界边缘情况是所有内部点等于端点最大值时。 考虑：```
4 1
5 5 5 5
1 4
```这里$H = 5$。 循环首先检查索引 2，发现$e_2 = 5 \ge 5$，并立即返回“否”。 这证实了平等必须阻碍可见性，而不仅仅是严格意义上更大的值。 

另一种情况是单点查询：```
3 1
10 1 2
2 2
```自从$i = j$，该算法完全跳过扫描并返回“是”，这与点始终对其自身可见的定义相匹配。 

最后，反转端点：```
3 1
1 100 1
3 1
```该算法交换索引，计算$H = 1$，并且仅检查索引 2。$100 \ge 1$，它正确输出“no”。
