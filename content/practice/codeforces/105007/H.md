 ## 解决方案
 ## 问题理解

 我们有一棵树$N$节点，其中每个节点代表具有固定美味值的美食。 鲍勃和查理两个玩家反复从当前树上摘下两片叶子。 对于每对选定的叶子，查理挑选其中一片来吃，而鲍勃则选择另一片。 两位玩家都具有完美的战略眼光，都希望最大限度地提高所吃食物的整体美味。 

这个过程一直持续到没有剩余的食物为止，这意味着每个节点最终都会被删除一次，并且每个删除步骤都会消耗一对叶子。 

输出是鲍勃在双方最佳发挥下的最终总美味。 

关键结构是移除总是涉及叶子，因此游戏受到树随时间收缩的方式的限制，而不是节点的任意配对的限制。 

约束条件$N \le 20$非常小。 这立即表明指数甚至阶乘搜索是可行的。 任何枚举节点子集或匹配的状态的解决方案都是可能可接受的。 然而，困难不在于枚举，而在于对最优对抗选择下的博弈动态进行正确建模。 

当多个叶子具有相同或极端值时，会出现微妙的边缘情况。 例如，考虑一棵星形树，其中一个中心连接所有叶子。 将最佳可用叶子在本地配对的天真贪婪方法会失败，因为删除叶子会改变哪些节点成为叶子，从而以依赖于全局结构而不是本地配对的方式改变未来的有效移动。 

另一种故障情况发生在路径中。 在链中，叶子始终是端点，因此早期的选择严重限制了未来可用的对。 贪婪的“总是取两个最大的叶子”方法会失败，因为它忽略了删除节点可以创建或破坏影响未来回合的叶子机会。 

## 方法

 直接的暴力方法将逐步模拟游戏。 在任何时刻，我们都会识别所有叶子，选择其中两个，然后根据哪个玩家拿走哪个叶子进行分支。 我们递归地继续，直到树为空。 这在原则上是正确的，因为它探索了有效行动和结果的每一个可能的序列。 

然而，分支因子很大。 即使在一棵小树中，也可以有多个叶子，并且在每一步中我们选择一对，然后以两种方式分配它们。 州的数量呈超指数增长$N$，因为每次删除都会改变树结构和叶子集。 即使与$N = 20$，对删除序列的简单递归将超出可行的限制。 

关键的观察是，在任何时候唯一重要的是当前剩余节点集，以及我们通过选择排序隐式评估其轮次效果。 自从$N$很小，我们可以将剩余节点表示为位掩码。 树结构可以进行预处理，并且在任何状态下，我们都可以通过检查它们是否仍然有最多一个活动邻居来计算哪些节点是叶子。 

一旦我们修复了一个状态，下一步的行动就明确了：选择任何无序的当前叶子对，然后选择哪个值传给 Bob，哪个值传给 Charlie。 这自然会导致子集上的极小极大 DP。 鲍勃正在最大化他的总收益，而查理则最小化鲍勃当前选择的配对分配的收益。 

我们记忆剩余节点的子集。 每个状态计算所有有效的叶对，模拟这两个分配，并递归。 

这将问题转化为具有对抗性配对决策的标准子集 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对序列进行强力模拟 | 指数级有效$O((N!)^2)$| O(N) | 太慢了 |
 | 具有叶对极小极大的子集 DP |$O(2^N \cdot N^3)$|$O(2^N)$| 已接受 |

 ## 算法演练

 1. 预先计算邻接信息并将其存储为位掩码以进行快速邻居检查。 这使我们能够在恒定或接近恒定的时间内测试一个节点是否是给定子集下的叶子。 
2. 对于节点的每个子集，定义一个函数$dp(mask)$代表Bob仍然可以从剩余节点中获得的最大总美味度`mask`。 这将游戏压缩成独立的子问题。 
3. 计算`dp(mask)`，首先识别出其中的所有节点`mask`那是叶子。 如果一个节点至多有一个邻居仍然存在，则该节点是叶子`mask`。 这种情况是通过计算活动邻居来评估的。 
4. 如果剩余节点数为0，则返回0。这是无法收集更多美味的最终状态。 
5. 枚举所有无序的不同叶子对$(u, v)$。 每对代表一个合法的举动。 
6. 对于每对$(u, v)$，考虑这两个作业：Bob 接受$u$查理采取$v$，或者鲍勃采取$v$查理采取$u$。 删除后，过渡到新的子集`mask' = mask without u and v`。 
7. 由于查理是敌对的，因此对于每一对，我们假设查理选择的分配使鲍勃的未来总数最小化。 因此，对于每一对，我们从鲍勃的角度来看这两个作业中最差的一个。 
8. 在所有可能的叶子对中，鲍勃选择使最终总增益最大化的一对。 将此值存储在`dp(mask)`。 

### 为什么它有效

 每个状态都完整地描述了一个有效的中间树配置。 游戏中唯一的决策点是接下来选择哪两片叶子，因为一旦选择了这对叶子，所有其他动作都将被强制。 DP 探索此类选择的所有有效的未来序列。 极小极大结构正确地模拟了查理的局部分配选择和鲍勃的全局配对选择。 由于每次转换都会严格减少节点数量，因此不存在循环，并且记忆可确保正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from functools import lru_cache

def solve():
    n = int(input())
    t = list(map(int, input().split()))
    
    adj = [0] * n
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    @lru_cache(None)
    def dp(mask):
        nodes = [i for i in range(n) if (mask >> i) & 1]
        if len(nodes) == 0:
            return 0

        # compute degrees inside mask
        deg = [0] * n
        for i in nodes:
            deg[i] = bin(adj[i] & mask).count("1")

        leaves = [i for i in nodes if deg[i] <= 1]

        if len(leaves) < 2:
            return 0

        best = 0

        m = len(leaves)
        for i in range(m):
            for j in range(i + 1, m):
                u = leaves[i]
                v = leaves[j]

                nxt = mask & ~(1 << u) & ~(1 << v)

                # Bob takes u, Charlie takes v
                bob1 = t[u] + dp(nxt)

                # Bob takes v, Charlie takes u
                bob2 = t[v] + dp(nxt)

                best = max(best, min(bob1, bob2))

        return best

    full = (1 << n) - 1
    print(dp(full))

if __name__ == "__main__":
    solve()
```该实现使用位掩码表示剩余零食的每个子集。 邻接也被压缩为位掩码，因此叶检测减少为按位交集和总体计数。 

DP 函数显式枚举当前叶，这是有效的，因为只有叶是可选择的。 每对叶子恰好生成一个游戏动作，并且递归调用评估结果配置。 

一个微妙的细节是`min(bob1, bob2)`表达。 这对鲍勃选择一对后查理的选择进行编码：查理将最差的结果分配给鲍勃，因此我们取鲍勃接收任一端点的最小值。

 ## 边缘情况

 一个最小的案例$N=2$只有一步棋，因此两个玩家只需选择一个节点即可。 该算法简化为评估一对叶子，并在查理做出选择后正确地为鲍勃分配最大可能的结果，因为`min(t1, t2)`直接决定了鲍勃的增益。 

在星形图中，最初所有外部节点都是叶子。 DP 评估所有叶对，但每次删除都会更改哪些节点仍保留为叶。 该算法根据减少的掩模正确地重新计算度数，确保新暴露的叶子包含在未来的过渡中。 

在路径图中，最初只有端点是叶子，但删除它们可以暴露新的端点。 子集 DP 自然地捕获了这一点，因为叶计算是从当前掩码而不是预先计算的静态结构导出的。
