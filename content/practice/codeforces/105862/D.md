 ## 解决方案
 ## 问题理解

 我们得到一个整数集合，并被要求查看通过取这些数字的任何子集并使用按位或将它们组合起来可以形成的所有值。 从这组可达结果中，我们需要确定从未作为结果出现的最小非负整数。 

重新表述该任务的一个有用方法是想象从零开始，并可选择通过“或”将每个数字“添加”到当前值中。 每个子集对应于是否包含每个元素的某种选择序列，并且该子集的 OR 生成单个值。 最终感兴趣的对象是所有此类 OR 结果的集合，我们正在寻找该集合中缺少的第一个整数。 

该问题中的约束是围绕按位或的结构而不是原始数字大小设计的。 即使值看起来很大，OR 也仅通过位进行交互，因此有效状态空间由表示最大值所需的位数决定。 这立即排除了任何显式枚举子集的方法，因为这将在元素数量上呈指数级增长。 相反，唯一可行的方法必须通过位掩码将问题压缩到可管理的状态空间中。 

如果仅考虑输入数组而不是子集 OR 结构，则很容易错过一些边缘情况。 如果数组仅包含零，则每个子集 OR 都为零，因此可达集为`{0}`答案应该是`1`。 一个天真的错误是假设每个元素都贡献一个新值，从而导致错误地认为存在多个不同的 OR 结果。 

当值在位中严重重叠时，会发生另一种微妙的情况。 例如，使用输入`[1, 2, 3]`，子集 OR 结果是`{0, 1, 2, 3}`因为`1 | 2 = 3`，但是没有办法形成`4`。 幼稚的方法可能会错误地假设，由于位 0 和 1 出现，所有直到`3`被覆盖并且墨西哥应该被覆盖`4`，但这只是正确的，因为`4`需要任何元素中都不存在的新位。 

最后，考虑全局 OR 密集但在可表示性方面仍存在差距的输入。 即使所有元素的 OR 是`7`，这并不意味着所有数字`0`到`7`是可达的。 “位覆盖率”和“值覆盖率”之间的不匹配是朴素推理失败的核心原因。 

## 方法

 暴力方法很简单：枚举数组的每个子集，计算其按位或，将所有结果存储在一个集合中，最后从零向上扫描以找到第一个丢失的整数。 这是正确的，因为它明确地构建了问题的定义。 然而，它需要迭代所有`2^n`子集，并为每个子集计算一个 OR 直到`n`最坏情况下的要素。 这导致大约`O(n * 2^n)`操作，即使对于`n = 25`，更不用说更大的约束了。 

关键的观察是，我们实际上并不关心哪个子集产生了值，只关心值是否可达。 这将问题转化为 OR 状态的可达性问题。 每个数字都会改变当前状态`x`进入新的状态`x | a_i`。 由于 OR 只添加位而从不删除它们，因此状态空间在重复转换下是封闭的，并且受输入可表示的最大位掩码的限制。 

这使我们能够将问题视为基于位掩码的动态编程：维护一个可实现 OR 值的布尔数组，并使用每个数组元素迭代扩展它。 每个元素都贡献从所有当前可到达状态的转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n·2^n) | O(n·2^n) | O(2^n) | O(2^n) | 太慢了 |
 | 位掩码 DP | O(n·2^B) | O(n·2^B) | O(2^B) | O(2^B) | 已接受 |

 这里`B`是表示数组中最大值所需的位数。 

## 算法演练

 1. 确定表示数组中任意值所需的最大位长度，并设置限制`MAX_MASK = 2^B`。 这定义了所有可能的 OR 结果的范围，因为 OR 不能引入新的位。 
2. 创建布尔数组`dp`在哪里`dp[x]`指示某个子集是否产生 OR 值`x`。 初始化`dp[0] = True`，代表空子集。 
3. 处理每个数字`a`在数组中。 对于每个当前可达到的值`x`，我们还可以达到`x | a`。 为了避免在同一迭代中覆盖信息，我们根据当前状态的快照计算更新。 
4.处理完所有元素后，扫描`dp`从`0`向上并返回第一个索引`mex`这样`dp[mex]`是假的。 

快照是必要的原因是，允许就地更新会在同一迭代中错误地多次链接单个元素，从而有效地模拟同一数组元素的重用，这违反了子集约束。 

### 为什么它有效

 该算法保持了处理第一个之后的不变量`i`元素，`dp[x]`当且仅当存在第一个的子集时才为真`i`OR 等于的元素`x`。 每次转变`x -> x | a_i`完全对应于决定是否包含`i`- 子集中的第一个元素。 由于每个子集决策每个元素只表示一次，因此不会错过任何可达的 OR 值，也不会引入无效值。 因此，最终扫描正确地识别出不能表示为子集 OR 的最小整数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    max_val = 0
    for x in arr:
        max_val |= x

    # number of bits needed to represent max_val
    B = max_val.bit_length()
    size = 1 << B

    dp = [False] * size
    dp[0] = True

    for a in arr:
        ndp = dp[:]  # snapshot
        for x in range(size):
            if dp[x]:
                ndp[x | a] = True
        dp = ndp

    for i in range(size):
        if not dp[i]:
            print(i)
            return

if __name__ == "__main__":
    solve()
```该实现首先将状态空间压缩为仅实际出现在输入中的那些位。 这避免了对无法到达的更高掩码进行不必要的工作。 

核心循环构建`ndp`从`dp`确保每个元素在每个子集决策中仅使用一次。 过渡`x | a`对当前元素的包含进行编码。 最终的线性扫描是安全的，因为 OR 状态空间在索引中是连续的，尽管可达性不是连续的。 

一个微妙的点是我们永远不需要显式地跟踪子集，只需要可达的 OR 值。 这使得解决方案能够保持在可管理的范围内`2^B`状态空间而不是指数空间`n`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n·2^B) | O(n·2^B) | 对于每个元素，我们扫描所有位掩码状态并传播 OR 转换 |
 | 空间| O(2^B) | O(2^B) | 我们存储每个可能的位掩码的可达性|

 价值`B`受输入值中的最大位数限制，这在实践中使状态空间保持较小。 这非常适合典型的约束，其中值高达约`10^6`或者`10^7`，最多给出 20-25 位。

 ## 边缘情况

 对于仅由零组成的输入，算法初始化`dp[0] = True`并且从不扩展它。 从零开始扫描发现`0`是可达的，但是`1`不是，所以输出是正确的`1`。 

对于所有值都是 2 的幂的输入，每个元素引入一个新位，并且 OR 转换逐渐填充这些位的组合。 DP 正确构建所有位子集，但任何需要多个相同位的数字都是不可能的，并且扫描会相应地检测第一个丢失的整数。 

对于数组已经包含一个大值的情况，例如`2^k`，该位立即通过 OR 传播到所有可达状态，但不保证填充中间值。 该算法仍然明确检查每个候选者，确保不对连续覆盖做出任何假设。
