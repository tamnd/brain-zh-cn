 ## 解决方案
 ## 问题理解

 问题要求我们取一个有高度的矩形网格`n`和宽度`m`，制作几个相同的副本，然后附加这些副本而不旋转它们。 最终组合的形状必须是正方形。 我们需要最少数量的副本来实现这一目标。 最初的问题来自 Codeforces，最多有`10^5`测试用例的尺寸大到`10^9`。 

输入描述了许多独立的矩形。 对于每个矩形，输出是这些矩形的最小计数，这些矩形可以平铺成更大的正方形，同时保留每个矩形的方向。 这些副本以类似网格的方式排列，所以如果我们放置`a`垂直复制并`b`水平复制，最终尺寸变为`(a * n) × (b * m)`。 要使其成为正方形，这两个值必须相等。 

大范围立即排除了模拟。 边长可以是十亿，因此尝试可能的正方形大小或重复添加矩形是不可能的。 和`10^5`测试用例时，我们需要一种方法，每个测试用例只执行少量恒定的算术。 

主要的边缘情况是当矩形已经是正方形时。 用于输入`1 1`，答案是`1`。 搜索更大排列的粗心方法可能会错误地返回更大的数字，但使用一个副本就已经满足了条件。 

另一种边缘情况是一侧将另一侧分开。 对于输入：```
1
2 4
```正确的输出是：```
2
```两份副本`2 × 4`矩形可以并排放置以创建一个`2 × 8`矩形，但那不是正方形。 相反，将它们一个放在另一个之上会给出`4 × 4`正方形。 仅检查水平放置的方法将会失败。 

一个更微妙的情况是维度不相关。 对于输入：```
1
2 3
```答案是：```
6
```最小的正方形有边长`6`。 我们需要一个方向三个副本，另一个方向两个副本，给出`6`矩形。 仅计算面积比的解决方案无法满足实际的平铺要求。 

## 方法

 一个简单的方法是尝试可能的副本数量。 假设我们放置`x`垂直复制并`y`水平复制。 最终的矩形有尺寸`x * n`和`y * m`，所以我们需要找到最小的`x * y`这样：```
x * n = y * m
```蛮力想法会尝试以下值`x`和`y`直到等式成立。 这是正确的，因为每种可能的排列都由某个对表示`(x, y)`。 然而，尺寸高达`10^9`，即使迭代一小部分可能值也太慢。 在许多测试用例中，操作数量会呈爆炸式增长。 

关键的观察是，我们实际上并不关心排列本身，只关心两个矩形尺寸可以划分的最小正方形边长。 最终正方形边长必须是以下的公倍数`n`和`m`。 可能的最小边是它们的最小公倍数。 

如果最终的正方形有边长`L`，则沿高度的副本数为`L / n`沿着宽度是`L / m`。 矩形的总数为：```
(L / n) * (L / m)
```为了尽可能最小的`L`，我们选择：```
L = lcm(n, m)
```使用关系：```
lcm(n, m) = n / gcd(n, m) * m
```份数变为：```
(n / gcd(n, m)) * (m / gcd(n, m))
```简化为：```
n * m / gcd(n, m)^2
```这直接给出了答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(最小正方形边) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(log(min(n, m))) | O(log(min(n, m))) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取矩形尺寸`n`和`m`。 

我们只需要这两个值，因为每种可能的最终排列取决于每个方向放置了多少个副本。 
2. 计算`g = gcd(n, m)`。 

最大公约数告诉我们两个维度已经共享了多少。 删除这个共享因素会留下最小的不兼容部分，这些部分决定了所需的副本数量。 
3. 计算两个轴上的副本数。 

垂直份数为`m / g`，水平方向上的数字是`n / g`。 将它们相乘得出矩形的总数。 

这样做的原因是最小的正方形边是最小公倍数。 两个轴必须缩放，直到尺寸满足该值。 
4、输出：```
(n / g) * (m / g)
```这是可能的最小计数。 

为什么它有效：每个有效的构造都会创建一个边长为 的公倍数的正方形`n`和`m`。 最小的长度是最小公倍数，因此任何其他方形结构必须至少使用同样多的副本。 该公式使用最小边长，这意味着它达到了最小值。 

## Python 解决方案```python
import sys
from math import gcd

input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, m = map(int, input().split())
        g = gcd(n, m)
        ans.append(str((n // g) * (m // g)))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```该代码读取所有测试用例并独立处理每个矩形。 这`gcd`函数就足够了，因为整个问题简化为寻找最小公倍数关系。 

表达式写为：```
(n // g) * (m // g)
```而不是：```
n * m // (g * g)
```因为先除法会使中间值更小。 Python 整数不会溢出，但这种形式也更清楚地反映了数学推理。 

唯一可能的错误是错误地使用最大公约数。 在相乘之前，必须从两个维度中删除共享部分，因为该共享部分代表垂直和水平方向的进步。 

## 工作示例

 对于矩形`2 × 3`：

 | 步骤| n | 米 | GCCD | 副本 |
 | ---| ---| ---| ---| ---|
 | 初始| 2 | 3 | 1 | 6 |
 | 决赛| 2 | 3 | 1 | 2 × 3 | 2 × 3

 最大公约数是`1`，这意味着没有共享因子。 最小的正方形边是`6`，需要沿一个方向复制三份，沿另一方向复制两份，总共需要`6`。 

对于矩形`6 × 8`：

 | 步骤| n | 米 | GCCD | 副本 |
 | ---| ---| ---| ---| ---|
 | 初始| 6 | 8 | 2 | 6 |
 | 决赛| 6 | 8 | 2 | 3 × 4 | 3 × 4

 共同因素`2`将问题简化为`3 × 4`。 最小的正方形边是`24`，所以我们需要`4`一个方向上的矩形和`3`在另一个。 

这些迹线显示了不变量：将两边除以 gcd 后，剩余的因子表示达到第一个公共正方形大小所需的精确缩放。

 | 测量 | 复杂性 | 说明|

 ## 边缘情况

 对于已经是正方形的情况：```
1
5 5
```最大公约数是`5`。 公式变为：```
(5 / 5) * (5 / 5) = 1
```只需要一个矩形，这是正确的。 

对于可分边：```
1
3 12
```最大公约数是`3`。 答案是：```
(3 / 3) * (12 / 3) = 4
```最后的正方形边长是`12`，由放置四个组成`3 × 12`垂直堆叠的矩形。 

对于互质边：```
1
4 7
```最大公约数是`1`，所以答案是：```
4 * 7 = 28
```正方形的边必须是`28`，需要沿一个轴七个副本，沿另一个轴需要四个副本。 由于不存在更小的公倍数，因此更小的排列是行不通的。
