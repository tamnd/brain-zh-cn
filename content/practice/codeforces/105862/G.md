 ## 解决方案
 ## 问题理解

 每个测试用例都描述了几天内重复的随机过程。 每天，跑步者独立选择 0 到 12 公里之间的整数距离，每个值都有自己的固定概率，以百分比形式给出。 超过$n$天，我们关心所有选定距离的总和，任务是计算这个总和恰好是的概率$x$。 

从计算的角度来看，这是一个经典的和分布问题：我们反复将相同的离散概率分布与其自身进行卷积$n$次，并且我们需要结果分布的单个系数。 

输入大小使结构清晰。 每个测试用例最多允许$n = 10^5$，以及所有的总和$n$跨测试达到$3 \cdot 10^5$。 这立即排除了任何试图模拟所有结果甚至在二次时间内天真地维持每个测试用例的完整分布的解决方案。 直接动态规划方法$O(n \cdot x)$转换也是不安全的，因为$x$可以达到$12n$，粗略地制作最坏情况的状态空间$1.2 \cdot 10^6$每个测试，并将其乘以$n$远远超出了可行的限度。 

核心难点是每天增加一个小的随机变量，我们需要总和的分布。 隐藏结构是支持度很小且固定，从0到12，这表明卷积可以大量优化。 

一些边缘情况揭示了为什么粗心的方法会失败。 

如果所有概率质量都为零，则答案很简单并且等于 1，当$x = 0$，否则为 0。错误归一化的简单卷积实现仍可能产生浮动错误或非整数模不一致。 

如果所有概率质量都在单个值（例如 12）上，则总和是确定性的并且等于$12n$。 任何错误地截断范围或移动索引的 DP 都可能很容易错过这种边界情况。 

如果$n$很大但是$x$很小，许多 DP 方法浪费时间填充永远无法到达的状态，这是我们需要消除的主要低效率。 

## 方法

 一个简单的方法是定义一个 DP，其中$dp[i][s]$是之后的概率$i$天，总和是$s$。 每天都会转变为 13 种可能的下一个状态，每种状态对应一种可能的距离。 这是正确的，因为它直接对流程定义进行编码。 

然而，这个公式的成本与状态数乘以转换成正比，大致如下：$O(n \cdot (12n) \cdot 13)$，因为总和范围与线性增长$n$。 在最坏的情况下，这会变成$10^5 \cdot 10^6$，这是完全不可行的。 

关键的观察是，我们处理的不是任意转换，而是固定的小步长卷积。 每天对当前分布应用相同的多项式乘法。 我们可以考虑 12 次多项式的重复卷积，而不是考虑 DP 层。 

这将问题转化为模运算下的高效多项式乘法。 由于多项式次数虽小但指数$n$很大时，我们避免简单求幂，而是使用分而治之或类似 FFT 的卷积策略。 然而，由于度数仅为 12，因此更快、更简单的方法是在分段上使用平衡的分而治之 DP，在每个合并步骤将结果与卷积相结合。 每次合并成本$O(13^2)$，这是常数，并且有$O(n \log n)$总共合并。 

这将指数重复转换为对数深度卷积树。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解 DP 的天数和总和 |$O(n^2 \cdot 13)$|$O(n^2)$| 太慢了 |
 | 分而治之卷积DP |$O(13^2 \cdot n \log n)$|$O(n \cdot 13)$| 已接受 |

 ## 算法演练

 我们将每天的分布视为多项式$P(x)$12 次，其中系数$P[k]$是$p_k / 100$。 最终的答案就是系数$x^x$在$P(x)^n$。 

1. 将每个分布表示为长度为 13 的数组。这编码了一天的概率质量函数。 
2. 定义一个递归函数来计算一段天数的分布。 对于一天，返回基础多项式。 
3. 将天数间隔分为两半，并递归计算每一半的分布。 这对应于计算$P^{len}$对于每个部分。 
4. 使用多项式卷积合并两个结果。 位置处的系数$s$合并分布中的值是通过对所有分割求和来计算的$i + j = s$，将左右段的概率相乘。 
5. 重复直到满量程$n$天已处理。 
6. 提取索引处的系数$x$，这是所需的概率。 

这种方法起作用的根本原因是独立和上的概率分布完全通过卷积组成。 每个递归合并都组合了独立的天数块，并且独立性保证了概率的乘法和总和的加法。 

保持的不变性是每个线段函数返回该线段长度上总距离的精确分布。 在合并时，独立性确保左右总和的所有组合都被精确地计算一次，并且不会遗漏或重复计算交叉项。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def inv(x):
    return pow(x, MOD - 2, MOD)

def convolve(a, b):
    res = [0] * 13
    for i in range(13):
        if a[i] == 0:
            continue
        for j in range(13):
            if b[j] == 0:
                continue
            if i + j < 13:
                res[i + j] = (res[i + j] + a[i] * b[j]) % MOD
    return res

def solve_case(n, x, p):
    base = [v * inv(100) % MOD for v in p]

    def build(k):
        if k == 1:
            return base
        half = build(k // 2)
        if k % 2 == 0:
            return convolve(half, half)
        else:
            return convolve(convolve(half, half), base)

    dp = build(n)
    return dp[x] if x < len(dp) else 0

t = int(input())
for _ in range(t):
    n, x = map(int, input().split())
    p = list(map(int, input().split()))
    print(solve_case(n, x, p))
```该代码使用 100 的模倒数将概率转换为模形式，因为每个百分比都是按比例缩放的。 卷积函数强制执行有界度 12 结构，确保没有不必要的状态扩展。 

递归求幂结构构建了分布$n$使用重复平方的天数，其中卷积代替乘法。 

一个微妙的点是固定大小的 13 数组，这可以防止溢出到无效的总和中。 任何超过 12 的索引都会被忽略，因为不可能在一天内出现，并且递归会在每个合并步骤中保留此界限。 

## 工作示例

 考虑一个小场景，其中$n = 3$,$x = 2$，且分布均匀$\{0, 1\}$，意味着每天以 1/2 的概率贡献 0 或 1。 

一天后，分布为：

 | 总和 | 概率 |
 | ---| ---|
 | 0 | 1/2 | 1/2
 | 1 | 1/2 | 1/2

 两天后：

 | 步骤| 0 | 1 | 2 |
 | ---| ---| ---| ---|
 | 第一天 | 1/2 | 1/2 1/2 | 1/2 0 |
 | 第 2 天 | 1/4 | 1/4 1/2 | 1/2 1/4 | 1/4

 三天后：

 | 步骤| 0 | 1 | 2 | 3 |
 | ---| ---| ---| ---| ---|
 | 合并 | 1/8 | 3/8 | 3/8 | 1/8 |

 该算法通过递归分裂来重现这一点$3$进入$1 + 2$，计算每一边，并进行卷积。 

现在考虑一种退化情况，其中所有概率质量均为 12。任意天数后的分布在索引处只有一个非零条目$12n$。 卷积步骤保留了这一点，因为将两个增量分布相乘会加性地移动索引，而不会扩散质量。

 ## 边缘情况

 当所有概率都集中在零时，每个卷积在索引 0 处保留一个非零系数。该算法处理此问题是因为卷积仅乘以零位置条目，而所有其他索引在整个递归过程中保持为零。 

当所有概率都集中在 12 时，每次合并都会通过加法精确地改变分布。 单个递归构建步骤会生成累积到索引的增量分布$12n$，并且其他索引处的任何查询都会正确返回零，因为这些位置在卷积过程中永远不会被填充。 

什么时候$x$超过$12n$，由于每个节点的固定大小 13 和有界合并，DP 数组从不分配这样的索引，因此最终访问安全地返回零，而不需要显式检查。
