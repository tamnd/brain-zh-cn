 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 在每个场景中，都有多组敌人，每组都有一定的初始大小。 游戏允许我们执行两种动作，我们想要最小化的成本是直到每组都被完全清除为止所使用的动作总数。 

第一个动作是对任意非空组进行单体攻击。 每次此类攻击都会增加一个全局计数器，用于跟踪我们在不使用终极技能的情况下连续累积的单次攻击次数。 

第二个动作是对一组进行终极攻击，但只有当所选组的怪物数量至少与该指示物的当前值相同时才能使用。 使用时，它会从所选组中移除相应数量的怪物，并将计数器重置为零。 

困难在于计数器取决于单次攻击的历史记录，而最终会消耗累积的值。 目标是安排单次攻击和终极攻击，以使操作总数最小化。 

约束很大：所有测试用例的组总数最多可达 200,000 个，组内的值最多可达 10^9。 这立即排除了任何试图对计数器的所有状态进行单独攻击或动态编程建模的模拟。 每个测试用例的任何解决方案都必须是线性或接近线性的。 

一种幼稚的方法可能会尝试模拟单一攻击和终极技能的所有可能序列，或者尝试在本地贪婪地决定何时触发终极技能。 但这会失败，因为“兑现”柜台的最佳时机取决于全局结构，而不仅仅是当前群体。 

典型的误导场景是小群体与大群体并存。 如果我们过早地积极使用终极技能，我们就会浪费潜在的反价值。 

例如，考虑这样的情况：```
n = 3
a = [1, 100, 1]
```如果我们尝试过早地重复重置计数器，我们可能永远不会构建足够大的值来有效地减少大组，从而导致不必要的操作。 

## 方法

 The key observation is that the only meaningful structure in the problem is the distribution of group sizes. 该计数器不与任何特定组绑定，因此我们可以自由地使用任何组来累积它，然后再将其花费在一个大组上。 

蛮力视角将模拟所有操作序列。 从由剩余群体大小和当前计数器定义的状态开始，我们分支要么执行单次攻击，要么在可能的情况下应用终极攻击。 这个状态空间非常巨大，因为计数器可以增长到 10^9，并且每个组大小都会导致许多转换。 Even with memoization, the number of distinct states is far too large to fit within constraints.

 关键的见解是扭转观点：不要考虑何时使用终极词，而是考虑它们实际代表什么。 大小为 a_i 的组上的大小为 x 的终极有效地允许我们将 x 个单次攻击“捆绑”为单个操作，但前提是我们已经通过之前的单次攻击积累了该 x 。 

这表明了一种配对结构：每次我们在终极攻击之前执行 k 个单次攻击，我们就有效地将 k 块与可以吸收它的组进行匹配。 The optimal strategy is to sort group sizes and reason about how many full “cycles” of accumulation we can apply across the array.

 排序后，我们从最大到最小处理组。 直觉是，较大的群体决定了计数器必须达到多大才有意义。 每次我们决定使用终极技能“覆盖”一个群体时，我们实际上是在选择阈值 x 并预先支付 x 次单次攻击。 

这将问题转化为维持我们必须总共花费多少次单次攻击，同时贪婪地决定我们通过终极重置的次数。 最佳结构最终是我们模拟跨排序组的累积操作，并始终尝试根据最大的剩余需求有效地重用累积计数器。

 ## 算法演练

 1. 按非降序对组大小数组进行排序。 This lets us reason about how demands accumulate from small to large without interleaving structure.
 2. 初始化变量`ops`计算总操作和变量`acc`代表我们已经累积但尚未消耗的单次攻击数量。 
3. 从最小组到最大组遍历排序数组。 
4. 对于每个团体的规模`a[i]`，决定当前累积计数器的多少可以通过大招“花费”。 如果`acc`相对于足够大`a[i]`，我们可以使用终极来有效地约简这个群； 否则我们必须通过单次攻击继续积累。 
5. 如果累积的计数器不够，我们模拟添加单个攻击，直到达到有用的阈值，同时增加两个攻击`acc`和`ops`。 
6. 当使用大招时，我们从组中减去所需的数量并重置`acc`归零，因为终极技能会重置组合。 这种重置至关重要，因为它可以确保未来的决策重新开始。 
7. 对所有组继续此过程，始终倾向于以尽可能最有利的方式重复使用累积计数器。 

其核心思想是，积累是一种可重用的资源，贪婪顺序确保我们永远不会将其浪费在较小的群体上，而以后可以更有效地使用它。 

### 为什么它有效

 在任何时刻，累积的计数器都代表尚未转换为终极攻击的连续的单一攻击块。 任何有效的策略都必须将所有单一攻击划分为这样的块，每个块都以最终或剩余使用结束。 排序确保我们始终按照不会在较小的约束上浪费潜在容量的顺序分配这些块。 由于较大的群体主导了可行性，因此延迟其处理只会增加所需的积累，而绝不会减少它。 这种单调结构保证了对排序值的贪婪扫描会产生最佳的操作划分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()

        ops = 0
        acc = 0

        for x in a:
            if acc >= x:
                acc -= x
                ops += 1
            else:
                ops += x - acc
                acc = 0
                ops += 1
                acc = 0

        out.append(str(ops))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```实现首先对每个测试用例进行排序，因为结构仅取决于相对大小。 变量`ops`和`acc`分别跟踪总操作和当前累积组合。 

对于每个群体，如果我们已经积累了足够的攻击，我们就直接通过大招“花费”它们，从而减少群体要求和反击。 否则，我们模拟建立足够的单一攻击来处理该组，并支付精确的差额以及终极本身的一项额外操作。 

的重置`acc`大招之后反映了使用第二种攻击后连击计数器被清除的游戏规则。 

一个微妙的点是，我们从不明确跟踪群体的部分消费； 每个组都在一个概念步骤中处理，因为进一步拆分它并不能提高贪婪排序下的最优性。

 ## 边缘情况

 当所有组的大小相等或几乎相等时，就会出现临界边缘情况。 在这种情况下，积累还是立即应用终极的决定在元素之间变得对称。 该算法通过按排序顺序处理来处理此问题，确保没有组过早地被迫进行次优重置。 

当一个极其庞大的群体支配所有其他群体时，就会出现另一种边缘情况。 在这里，最佳策略是从较小的群体中积累尽可能多的资金，然后再将其花在大的群体上。 排序处理保证了在处理大组之前所有较小的贡献都可用，从而防止浪费重置。 

最后的边缘情况是当 n = 1 时。该行为简化为直接解释，即准确累积该单个组所需的内容，确认贪婪逻辑正确退化为单周期计算。
