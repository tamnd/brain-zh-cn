 ## 解决方案
 ## 问题理解

 该问题给出了表示数据集的整数集合。 我们需要检查每个数字的第一个有意义的数字，即忽略符号后最左边的非零数字。 任务是判断数字是否`1`该前导数字比其他数字出现的频率更高。 如果是，则该数据集被视为可疑； 否则就不是。 

例如，数字`-4200`贡献领先数字`4`，因为减号不是数字的一部分，并且携带值的第一个数字是`4`。 数量`0`是一种特殊情况，因为它没有非零数字。 由于前导有效数字的定义不适用于零，因此零值不会对任何数字计数产生影响。 

输入大小是解决方案需要简单的主要原因。 由于数量高达数百万，我们只能承担与输入量成正比的工作。 任何将数字相互比较或以昂贵的方式重复扫描数字的方法很快就会变得太慢。 读取每个数字一次并提取其第一位数字就足够了。 

棘手的情况主要是如何正确提取数字。 一些数字，例如`-1000`必须算作领先`1`， 不是`-`或者`0`。 像这样的数字`0`不得意外增加某些数字的计数。 输入中第一位数字不唯一的数字也可能会导致不正确的比较。 

考虑输入：```
3
0 0 1
```正确的输出是：```
suspicious
```只有号码`1`贡献，所以数字`1`出现一次，所有其他数字出现零次。 将零视为具有前导数字的粗心实现`0`在这里仍然会通过，但在存在许多零的情况下会失败。 

再举个例子：```
4
0 0 0 1
```正确的输出是：```
suspicious
```零不应该与数字竞争`1`。 将零计算为前导数字会错误地生成数字`0`赢。 

负值也需要注意：```
2
-999 100
```正确的输出是：```
suspicious
```前导数字是`9`和`1`。 在提取数字之前必须忽略该符号。 

## 方法

 直接的暴力方法将收集每个数字的前导数字并重复比较频率以确定数字是否`1`是最大的。 这是正确的，因为唯一需要的信息是每个前导数字的频率。 但是，如果通过将每个数字的每个数字与其他数字进行比较来实现比较，则它可能会变得不必要的大。 和`n`数字，这种风格可以到达周围`10n`操作，这在这里仍然不可怕，但它错过了问题的更简单的结构。 

有用的观察是只有十个可能的前导数字。 我们不需要存储数字或执行复杂的比较。 我们只需要一个大小为 10 的频率数组。 在读取每个数字时，我们找到其前导有效数字并递增相应的计数器。 处理完整个数据集后，我们比较位数`1`与其他九位数字中的最大计数。 

暴力法之所以有效，是因为答案仅取决于数字频率，但它需要花费精力反复检查可以立即总结的信息。 频率阵列将问题简化为对输入的单次传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(10n) | O(10n) | O(1) | O(1) | 理论上可以接受，但没有必要 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 创建一个包含十个计数器的数组，其中索引`d`存储有多少个数字具有前导数字`d`。 
2. 读取每个数字，如果是负数，则去掉符号。 绝对值就足够了，因为前导数字仅取决于大小。 
3. 如果数字为零，则忽略它，因为它没有有效的前导数字。 
4. 对于每个非零数字，重复删除最后一位数字，直到只剩下第一位数字。 增加该数字的计数器。 
5. 所有数字处理完毕后，比较位数`1`每隔一个数字计数。 如果它严格大于所有这些，则打印`suspicious`; 否则打印`unfortunately not`。 

这样做的原因是该问题仅询问前导数字的分布。 该算法准确地保留了这些频率，而不保留其他任何内容。 一旦知道了计数，就可以通过一次比较来确定答案。 

为什么它有效：

 不变的是，在处理输入的任何前缀之后，频率数组包含处理的数字中每个前导有效数字的准确出现次数。 每个处理过的非零数字对其真实前导数字的计数器只贡献一次，而零则不贡献任何内容。 处理完所有数字后，不变量给出完整的频率分布，因此检查数字是否`1`具有最大的频率正好给出所需的结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)

    cnt = [0] * 10

    nums = input().split()
    for s in nums:
        x = int(s)
        if x == 0:
            continue

        x = abs(x)
        while x >= 10:
            x //= 10

        cnt[x] += 1

    for d in range(10):
        if d != 1 and cnt[1] <= cnt[d]:
            print("unfortunately not")
            return

    print("suspicious")

if __name__ == "__main__":
    solve()
```该代码仅存储十个计数器，因为可能的答案是以下数字`0`到`9`。 输入的数字会立即处理，因此无需将整个数据集保留在内存中。 

这`abs`call 消除了负号的影响。 除以十的循环从一个整数移向它的第一个数字。 例如，`58320`变成`5832`， 然后`583`， 然后`58`， 然后`5`。 

零检查发生在此过程之前，因为重复除零会使其永远为零，从而错误地将其视为有效的前导数字。 最后的循环使用严格比较。 如果另一个数字与数字有相同的频率`1`, 数字`1`出现的频率并不高，所以答案一定是否定的。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log A) | O(n log A) | 每个数字都通过除以十来减少，其中`A`是数字的绝对值。 由于位数是有界的，因此这实际上是 O(n)。 |

 即使对于非常大的整数，最大位数也很小，因此每个输入值的处理量都很小。 该算法很容易满足预期的限制，因为它只对数据集执行一次遍历。

 ## 边缘情况

 对于这个案例：```
3
0 0 1
```该算法跳过两个零，然后提取前导数字`1`从最终的数字来看。 计数数组变为`cnt[1] = 1`所有其他计数保持为零，所以答案是`suspicious`。 

对于这个案例：```
2
-999 100
```该算法转换`-999`进入`999`, 提取数字`9`，然后提取数字`1`从`100`。 计数是`cnt[9] = 1`和`cnt[1] = 1`。 由于数字`1`是相连的而不是严格更大，答案是`unfortunately not`。 

对于每个值都以相同数字开头的大型集合，例如：```
5
700 71 7999 0 -7123
```该算法计算前导数字的四次出现`7`并忽略零。 数字`1`不超过该计数，因此它正确地拒绝了数据集。 这捕获了仅检查数字是否存在的解决方案`1`出现频繁，而不是检查它是否比其他数字出现得更频繁。
