 ## 解决方案
 ## 问题理解

 该问题询问是否可以将一组杂货分装在两个袋子中，以使两个袋子中的总重量完全相同。 每件物品必须放入一个袋子中。 输入给出物品的数量和每个物品的重量，输出是是否存在这样的划分。 

关键细节是所有物品的总重量足够小，以使目标总和易于管理。 尽管项目数量可以达到 100，但总权重不会超过 1000。这立即表明，依赖于总权重而不是可能子集数量的解决方案是合理的。 尝试每个子集的强力解决方案需要最多$2^{100}$选择，这远远超出了比赛所能进行的范围。 解决方案围绕$O(N \times S)$， 在哪里$S$是总重量，很容易接受，因为$S$最多为 1000。 

一些边缘情况可能会破坏粗心的实现。 第一个是奇数总重量。 对于输入：```
3
1 2 4
```正确的输出是：```
no
```因为两个袋子各需要装 7 的一半，这是不可能的。 仅检查某个子集是否存在而不考虑所需的一半的解决方案可能会给出错误的结果。 

另一种情况是总数为偶数但唯一可能的分割使用单个项目。 对于输入：```
3
1 2 3
```正确的输出是：```
yes
```因为一个袋子可以容纳重量为 3 的物品，另一个袋子可以容纳重量为 1 和 2 的物品。假设两个袋子都需要多个物品的实现将会失败。 

最后一个常见错误是忘记项目是单独的对象。 为了：```
3
100 100 100
```输出是：```
no
```总数为 300，但没有一个子集的权重为 150。仅计算可能的权重总和而不正确跟踪可实现的总和可能会导致错误的结论。 

## 方法

 直接的方法是尝试将所有可能的物品分配到第一个袋子中。 每个项目有两个选择，所以$N$这创建的项目$2^N$可能的分布。 对于每个分布，我们可以计算一个袋子的重量并检查它是否等于总数的一半。 这是正确的，因为它探索了分割项目的所有可能的方法。 问题在于操作次数。 和$N = 100$，搜索空间约为$1.27 \times 10^{30}$，这是不可能遍历的。 

有用的观察结果是，限制因素是权重，而不是项目数量。 我们只关心选择某些物品能否形成一定的总重量。 由于最终目标最多为 500，因此我们可以在一项一项处理时存储所有可达的和。 这将问题转化为子集和问题。 

蛮力之所以有效，是因为它会检查每个可能的子集。 由于子集太多而失败。 观察到总权重很小，我们可以用代表所有可实现权重的动态编程状态来代替对子集的搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^N) | O(2^N) | O(1) | O(1) | 太慢了|
 | 动态规划| O(N × S) | O(S)| 已接受 |

 ## 算法演练

 1.读取所有物品的重量并计算总重量。 如果总重量为奇数，则立即输出`no`因为两个相等的袋子需要非整数的一半。 
2. 目标重量为总重量的一半。 创建一个动态规划数组，其中`dp[x]`意味着可以选择一些总重量恰好为的加工物品`x`。 
3. 初始化`dp[0]`为 true，因为不选择任何项目会产生总和为零。 
4. 处理每件物品的重量。 对于每个可能的当前总和，更新添加此项是否会创建新的可达总和。 迭代必须从较大的总和减少到较小的总和，以便同一个项目不会被多次使用。 
5. 所有项目处理完毕后，检查`dp[target]`。 如果属实，则一个袋子中有一个物品子集的重量与目标重量完全相同，因此另一个袋子自动具有相同的重量。 

为什么它有效：不变的是在处理完项目的任何前缀后，`dp[x]`当该前缀的某个子集具有总权重时为真`x`。 最初对于空前缀来说这是正确的。 当考虑新项目时，每个旧的可达总和要么通过忽略该项目来保持可达性，要么通过获取该项目来创建新的可达总和。 因为我们向后更新，所以该项目不能贡献多次。 处理完所有内容后，目标状态准确表示是否存在有效的第一个包。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)
    weights = list(map(int, input().split()))

    total = sum(weights)

    if total % 2:
        print("no")
        return

    target = total // 2
    dp = [False] * (target + 1)
    dp[0] = True

    for w in weights:
        for s in range(target - w, -1, -1):
            if dp[s]:
                dp[s + w] = True

    print("yes" if dp[target] else "no")

if __name__ == "__main__":
    solve()
```该解决方案首先计算总重量，因为目标状态由最终平衡要求确定。 奇数总检查避免了不必要的动态编程工作，并立即处理不可能的情况。 

这`dp`数组仅存储从零到总数一半的值，因为高于目标的总和永远不会成为有效答案的一部分。 反向循环是关键的实现细节。 如果循环向上移动，则可以将权重添加到在同一迭代期间使用同一项目创建的总和中，这将错误地允许多次使用同一项目。 

Python 整数在这里不存在溢出问题，因为最大存储值只有 1000，但限制数组大小仍然使实现简单高效。 

## 工作示例

 对于第一个样本：```
6
30 100 70 20 1 21
```总数为 242，因此目标为 121。 

| 已加工项目 | 重量 | 新达到的目标状态 |
 | --- | --- | --- |
 | 开始| 0 | 0 |
 | 30| 30| 30|
 | 100 | 100 100 | 100 100、130 |
 | 70 | 70 70 | 70 70、100、121 |
 | 20 | 20 | 20、30、50、70、90、120 |
 | 1 | 1 | 121 变得可达 |
 | 21 | 21 21 | 21 121 仍可联系 |

 动态规划发现可以组成121，例如权重为100、20和1。其余项目的总和也是121，所以答案是`yes`。 

对于第二个样本：```
3
100 100 100
```总数为 300，因此目标为 150。 

| 已加工项目 | 重量 | 150 可以联系到吗？ 
| --- | --- | --- |
 | 开始| 0 | 没有 |
 | 100 | 100 100 | 100 没有 |
 | 100 | 100 200 | 200 没有 |
 | 100 | 100 300 | 300 没有 |

 没有子集创建权重 150，因此输出为`no`。 这说明了为什么仅检查总数是否为偶数是不够的。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N × S) | 每个项目都会将所有可能的总和更新为目标，其中 S 是总重量限制。 |
 | 空间| O(S)| DP 数组为每个可能的和存储一个布尔值。 |

 最大总权重仅为 1000，因此动态规划最多执行 100,000 次左右的转换。 这完全在限度之内。

import sys
import io

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    weights = list(map(int, input().split()))

    total = sum(weights)
    if total % 2:
        return "no\n"

    target = total // 2
    dp = [False] * (target + 1)
    dp[0] = True

    for w in weights:
        for s in range(target - w, -1, -1):
            if dp[s]:
                dp[s + w] = True

    return ("yes" if dp[target] else "no") + "\n"

assert solution("6\n30 100 70 20 1 21\n") == "yes\n"
assert solution("3\n100 100 100\n") == "no\n"

assert solution("1\n1\n") == "no\n"
assert solution("4\n5 5 5 5\n") == "yes\n"
assert solution("5\n1 2 4 8 16\n") == "no\n"
assert solution("6\n1 2 4 8 16 31\n") == "yes\n"

 ## 边缘情况

 对于总奇数情况：```
3
1 2 4
```该算法计算出总共 7。由于 7 不能分成两个相等的整数权重，因此返回`no`在构建 DP 表之前。 

对于单项拆分情况：```
3
1 2 3
```目标是 3。处理权重使得`dp[3]`考虑最后一项后为 true，因此算法返回`yes`。 它不要求两个袋子包含相同数量的物品，只要求相同的重量。 

对于重复权重：```
3
100 100 100
```目标是 150。DP 状态变为 100，然后是 200，然后是 300，但从未达到 150。 该算法正确地拒绝了该排列，而不是假设偶数总数就足够了。
