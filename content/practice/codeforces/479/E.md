 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 的一行楼层。 我们从 a 层开始，正好进行 k 步。 每次移动都会选择一个与当前楼层 x 不同的新楼层 y，但有一个限制：与禁止楼层 b 相比，我们不允许在绝对距离上移动“太远”。 形式上，只有当距离 |x − y| 时，我们才能从 x 到达 y 严格小于 |x − b|。 

每次移动后，我们都会记录访问过的楼层。 我们被问到 k 个记录楼层可能有多少种不同的序列。 

关键对象不仅仅是位置，而是允许的下一步移动集合取决于 b 相对于当前位置的位置。 如果我们距离 b 很远，则允许进行多次移动。 如果我们接近的话，允许的区域就会急剧缩小。 

约束 n, k ≤ 5000 立即排除任何显式枚举序列的方法。 即使每步分支大约 n 个选择也会导致 n^k 个状态，这是一个天文数字。 正确的解决方案必须重用重叠的子问题：经过相同次数的移动后，许多不同的路径通向同一楼层。 

当起始位置已经接近 b 时，会出现微妙的边缘情况。 例如，如果 a = b − 1，则唯一允许的方向是远离 b，并且许多中间位置变得不可能。 相反，如果a距离b很远，则第一个动作非常灵活，但后面的动作可能会“陷入”一个缩小的区域。 任何贪婪或基于模拟的计数都会失败，因为它忽略了到达同一楼层的不同历史的组合爆炸。 

另一个陷阱是忘记序列是通过其完整路径来区分的，而不仅仅是端点。 如果两条路径的中间步骤不同，则以同一楼层结束的两条路径将分别计数。 

## 方法

 暴力策略将模拟从 a 开始的所有 k 步路径。 从当前楼层 x 开始，我们尝试所有满足约束的 y 并递归地继续。 这在原则上是正确的，因为它完全遵守转换规则。 然而，状态的数量就像一棵树一样增长，其中每个节点可以分支到 O(n)，深度为 k。 即使进行剪枝，路径数量也会以 k 为指数，这对于 k 达到 5000 来说是不可能的。 

关键的观察结果是，该规则仅取决于到 b 的距离，而不取决于楼层的绝对同一性。 如果我们知道某个位置是在 b 的左边还是右边，以及距离有多远，我们就可以用间隔来表征转换。 

从位置 x 开始，所有有效的移动都恰好是那些比 b 更接近 x 的楼层。 如果我们定义 d = |x − b|，则有效目的地是区间 (x − d + 1, x + d − 1) 内的所有楼层，不包括 x 本身。 这会将每个状态转换为线路的连续段上的转换。 

我们不是单独枚举转换，而是维护一个动态编程表 dp[t][x]：t 次移动后到达 x 层的方式数。 每个州将其计数分布在一系列目的地上。 这是一个经典的“范围更新到点查询”结构，可以使用差异数组或前缀和来解决。 

对于每个 x，我们计算其有效区间 [L, R]，围绕 x 本身进行分割，并将 dp[t][x] 添加到该区间内除 x 之外的 y 的所有 dp[t+1][y]。 使用 dp[t+1] 上的差分数组，每个状态在 O(1) 中做出贡献，并且我们使用前缀和重建实际值。 

每层的过渡结构保持线性，因此总复杂度变为 O(nk)。

 | --- | --- | --- | --- |
 | 蛮力 | O(n^k) | O(n^k) | O(k) 递归 | 太慢了 |
 | DP 范围更新 | O(nk) | O(nk) | O(n) | 已接受 |

 ## 算法演练

1. 定义 dp[x] 为当前移动次数后到达 x 层的方式数。 最初，dp[a] = 1，因为我们从单个已知位置开始。 
2. 对于从 1 到 k 的每个步骤，创建一个初始化为零的新数组 ndp。 这将累积下一步动作的所有转换。 
3. 对于每个楼层 x，计算其允许的移动半径 d = |x − b|。 这决定了我们可以远离 x 多远。 
4. 将其转换为有效目的地的区间：所有 y 使得 |x − y| < d，变为 y ∈ [x − d + 1, x + d − 1]，不包括 x 本身。 
5. 不要单独向每个 y 添加 dp[x]，而是使用差异数组对 ndp 执行范围更新：在左边界添加 dp[x]，并在右边界后减去它，围绕 x 进行分割以将其排除。 
6. 处理完所有 x 后，通过 ndp 获取前缀和以重建每个楼层的实际计数。 
7. 将 dp 替换为 ndp 并继续下一步。 

经过 k 次迭代后，不需要 sum，因为每个 dp[x] 已经表示以 x 结尾的完整序列，并且答案是所有 x 的总和。 

### 为什么它有效

 在每一步中，dp[x] 都会聚合以 x 结尾的所有不同历史记录。 转换规则仅取决于 x 和 b，而不取决于 x 是如何到达的。 这使得过程成为马尔可夫式的：所有在 x 处合并的路径除了它们的计数之外都变得无法区分。 范围更新保留精确的重数，因为每个 dp[x] 独立分布到所有有效的下一个位置。 排除 x 可确保不计算无效自循环。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, a, b, k = map(int, input().split())
    
    dp = [0] * (n + 1)
    dp[a] = 1

    for _ in range(k):
        diff = [0] * (n + 3)

        for x in range(1, n + 1):
            val = dp[x]
            if not val:
                continue

            d = abs(x - b)
            if d <= 1:
                continue

            L = max(1, x - d + 1)
            R = min(n, x + d - 1)

            # add to [L, R]
            diff[L] = (diff[L] + val) % MOD
            diff[R + 1] = (diff[R + 1] - val) % MOD

            # remove x itself
            diff[x] = (diff[x] - val) % MOD
            diff[x + 1] = (diff[x + 1] + val) % MOD

        ndp = [0] * (n + 1)
        cur = 0
        for i in range(1, n + 1):
            cur = (cur + diff[i]) % MOD
            ndp[i] = cur

        dp = ndp

    print(sum(dp[1:]) % MOD)

if __name__ == "__main__":
    solve()
```dp数组表示每次移动后路径的分布。 差异数组对每个起始楼层的范围添加进行编码，前缀和有效地重建实际值。 

x 周围的分割是最微妙的部分。 单个区间 [L, R] 包括 x，因此我们通过仅在位置 x 处减去 dp[x] 进行补偿，同时保持区间的其余部分不变。 

所有算术均以 1e9+7 为模进行，以防止溢出并满足问题要求。

 ## 边缘情况

 当 x 距离 b 正好一步时，就会出现一种重要的边缘配置。 例如n=5，b=3，x=2。 这里d=1，条件|x-y| < 1 根本不允许整数 y。 DP 正确地从这些状态产生零贡献，因为计算的间隔崩溃并且差异更新取消了一切。 

另一种情况是当x远离b时，例如x=1且b=n。 那么 d 就很大，除了 x 本身之外，几乎整个范围都是允许的。 范围更新通过应用完整间隔并在 x 处减去来干净地处理此问题，确保所有有效目的地收到相同的贡献而无需重复计算。 

最后一个微妙的情况是差值数组中负值的累积。 因为我们在边界处进行减法，所以中间值可能会变为负值，但前缀求和之前的模归一化可确保正确性。
