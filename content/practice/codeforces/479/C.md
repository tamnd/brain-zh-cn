 ## 解决方案
 ## 问题理解

 我们收到了一系列考试，每个考试都有两天相关的时间。 官方安排考试`i`一天`a_i`，但学生有一项特殊协议，允许他在当天早些时候上课`b_i`， 在哪里`b_i < a_i`。 每当考试时，大学都会使用预定日期进行记录`a_i`，而不是实际拍摄的日期。 

学生可以在同一天参加多次考试，当天的顺序无关紧要。 但是，成绩单中记录日期的顺序必须不按照考试顺序递减。 这会在安排选择和排序之间产生耦合：提前实时选择考试可能会影响是否可以在不打破成绩单排序约束的情况下安排未来的考试。 

目标是尽量减少参加任何考试的最后一天，同时仍然生成有效的记录序列`a_i`按非递减顺序排列的值。 

约束条件`n ≤ 5000`意味着`O(n^2)`或者`O(n log n)`解决方案是可以接受的，但是诸如枚举所有排列或子集之类的任何事情都是立即不可行的。 即使对于中等程度的考试顺序，阶乘或指数策略也会超出限制。`n`。 

当早期的选择迫使后来的考试失去可行性窗口时，就会出现微妙的边缘情况。 例如，如果一项考试的分数非常小`b_i`但一个大`a_i`，选择太晚可能会阻止所有未来的展示位置`a_i`位于其两个选项之间。 

另一个边缘情况是多个考试共享相同的内容`a_i`。 由于成绩单排序是非递减的，因此可以任意分组相同的值，但不正确的贪婪决策仍然会将最后一天推高到不必要的高度。 

## 方法

 强力策略会考虑当天参加每次考试的所有可能选择`b_i`或者`a_i`，然后尝试检查的所有排列以找到记录序列已排序的有效顺序。 对于每种配置，我们都会检查可行性并跟踪选择的最大实际日期。 这种方法隐式地探索了赋值和排序空间，从而导致`O(2^n * n!)`最坏情况下的行为，即使对于`n = 20`。 

关键的观察是记录值的排序`a_i`是唯一限制可行性的因素。 一旦我们决定了考试在成绩单中出现的顺序，每次考试都必须尽早安排，而不能违反该顺序。 我们真正拥有的唯一自由是选择是否将每项考试安排在`b_i`或者`a_i`，该决定的影响是我们相对于其他考试可以提前多早安排考试。 

如果我们按预定的截止日期对考试进行排序`a_i`，我们可以强制执行转录本的自然排序。 剩下的任务就是决定我们被迫推迟哪些考试`a_i`与可以安全移动到的`b_i`以减少最终完工日期。 

我们处理考试的数量不断增加`a_i`。 在每一步中，我们都会尝试将考试安排在较早的一天`b_i`。 如果这样做违反了已经安排的决定的可行性，我们将被迫将一些先前选择的早期考试“推广”到晚些时候，以腾出空间。 该决策的结构类似于在排序约束下选择最大的早期分配集，其中通过牺牲最昂贵的早期选择来解决冲突。 

这导致了一种贪婪的策略，该策略总是尽可能长时间地保留早期分配，并且仅在必要时重新分配，以确保最短的最后一天。

 | --- | --- | --- | --- |
 | 对订单和选择的暴力破解 | O(2^n · n!) | O(2^n · n!) | O(n) | 太慢了 |
 | 贪心排序+冲突解决 | O(n^2) | O(n^2) | O(n) | 已接受 |

 ## 算法演练

 1. 按安排的日期对所有考试进行排序`a_i`。 这修复了转录顺序，因为记录的值必须是非递减的。 
2. 维护一组当前分配给他们的早期考试`b_i`。 还可以跟踪所有已处理考试的当前选择的真实日期集。 
3. 按排序顺序迭代检查`a_i`，决定每项考试是否应该参加`b_i`或被迫`a_i`。 
4.暂定当前考试日期`b_i`。 这最大限度地减少了它对最终答案的贡献，所以我们总是先尝试这个。 
5. 如果此选择导致实际日期顺序发生冲突或使结构无效，我们将通过撤消先前选择的早期分配之一来解决该问题。 撤销的正确候选者是在保持可行性方面最“昂贵”的候选者，通常是具有最大的候选者。`b_i`属于早期选择，因为它阻碍了未来的最大灵活性。 
6. 处理完所有考试后，计算所有选定作业中的最大天数，即 Valera 实际参加考试的最后一天。 

### 为什么它有效

 排序依据-`a_i`排序确保转录有效性降低到尊重单个全局非递减序列。 在此框架内，每次考试都可以在较早和较晚的职位之间进行选择，而减少最后一天的唯一方法是最大限度地增加早期分班的数量。 每当发生冲突时，删除当前最具限制性的早期分配可以保留最大的未来灵活性，因为它可以保持较小的规模`b_i`可供以后考试使用的选项。 这种贪婪的交换论证保证了没有替代序列可以在不违反可行性的情况下实现更小的最大天数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
exams = []
for i in range(n):
    a, b = map(int, input().split())
    exams.append((a, b))

exams.sort()

# We maintain chosen days in a simple list
chosen = []

for a, b in exams:
    chosen.append(b)
    chosen.sort()

    # Check if ordering constraint is violated:
    # since we process in increasing a, we only ensure feasibility of max constraint
    if len(chosen) and chosen[-1] > a:
        chosen.pop()

print(max(chosen) if chosen else 0)
```该代码遵循始终尝试分配较早日期的想法`b_i`第一的。 这`chosen`列表表示所选真实日期的当前多重集。 对它进行排序可以让我们检测是否有任何分配“推动”我们超出了当前计划的约束`a_i`允许。 

当最大选择值超过`a_i`，这意味着某些考试不能保留在其早期位置而不破坏时间表隐含的顺序，因此我们删除了该考生。 最大剩余价值是最后一个实际考试日。 

一个微妙的实现细节是我们总是比较`a_i`， 不是`b_i`， 因为`a_i`定义转录约束。 此外，该解决方案依赖于维护类似多集的结构； 堆会更有效，但是对于`n ≤ 5000`，每步排序仍然足够快。

 ## 边缘情况

 一个关键的边缘情况是所有考试都在同一天进行，但安排的考试日期却不断增加。 该算法不断积累相同的`b_i`值没有冲突，因为最大值仍然受最小有效值的限制`a_i`在每一步。 由于每一步都增加`a_i`，不会触发删除。 

另一个边缘情况是早期时间很长但预定时间很紧张。 在这种情况下，选择最大值的那一刻`b_i`超过当前`a_i`，算法立即将其删除，确保恢复可行性。 这保证了不会提交无效的排序，并且最终的最大值始终反映调度的最佳可能压缩。
