 ## 解决方案
 ## 问题理解

 我们有几堆单位立方体，每堆都有一个初始高度。 只需一次移动，我们就可以从一堆顶部取出一个立方体并将其放置在另一堆顶部。 随着时间的推移，这使我们能够在堆栈之间重新分配立方体，但每次移动一次只能移动一个立方体，并且不会创建或销毁立方体。 

我们关心的数量是塔高度的分布，定义为最多执行给定次数的移动后最高塔和最矮塔之间的差异。 我们希望最大限度地减少这种传播，并且还需要输出能够实现最佳结果的一系列动作。 

关键的困难在于每次操作仅移动一个立方体，因此大量改变塔的高度需要许多步骤，并且我们受到少量移动预算的限制。 

限制很小：最多 100 个塔和最多 1000 次移动。 这立即排除了任何尝试组合探索操作序列或模拟贪婪逐步改进之外的任何解决方案。 对所有动作序列的简单模拟在深度上是指数级的并且是不可能的。 

一个微妙的边缘情况来自这样一个事实：移动立方体会暂时增加不稳定性。 例如，如果我们从中间的塔上移动一个立方体，我们可能会先恶化扩散，然后再改善它。 只接受立即改进的贪婪策略将会失败。 

当所有塔已经具有相同高度时，会出现另一种角点情况。 在这种情况下，任何举动都无法改善答案，任何不必要的重新分配只会浪费操作。 例如，输入`4 10 / 5 5 5 5`应立即恢复不稳定状态`0`零动作。 

最后，在某些情况下，最佳平衡需要同时使用最高和最短的塔。 一次只修复一个极端的贪婪策略可能无法在移动限制内收敛。 

## 方法

 一个蛮力的想法是模拟最多 k 个动作的所有可能序列。 根据给定的塔高度配置，每次移动都会选择一对有序的塔，从而产生最多 n(n−1) 个可能的下一个状态。 即使 n = 100 且 k = 1000，搜索空间也会爆炸到天文数字。 仅分支因素就使这成为不可能。 

关键的观察结果是，最终目标不是关于单个塔，而是关于减少最大和最小高度之间的差异。 每次移动都会将一个单位从一座塔转移到另一座塔，因此每次操作都会将一座塔减少 1，另一座塔增加 1。这意味着我们可以从逐渐压平极值的角度来思考。 

如果一座塔高于当前的平均目标，那么它就是一个超额来源。 如果在下面，则为水槽。 经过多次操作后，最佳的最终配置将始终尽可能接近平均高度，因为总和是固定的，并且我们正在重新分配质量。 

这表明了一种贪婪策略：重复地将一个立方体从当前最高的塔移动到当前最短的塔。 每一次这样的举动都会缩小极端之间的差距，或者至少将两端推向中间。 由于我们总是选择最极端的对，所以我们从不浪费一步。 

我们模拟这个过程最多 k 个步骤，在每次操作后重新计算当前的最小值和最大值。 因为 n ≤ 100，所以线性扫描足够便宜。

 | --- | --- | --- | --- |
 | 暴力搜索 | 指数| 指数| 太慢了 |
 | 贪婪极限平衡 | O(k·n) | O(n) | 已接受 |

 ## 算法演练

 我们维护塔高度列表并重复执行最多 k 次操作。 

1. 计算当前最大塔和当前最小塔的索引。 

这确定了系统中最不平衡的货币对，它始终是最有利可图的调整货币对。 
2. 如果最大值和最小值之差是 0 或 1，我们就提前停止。 

此时，没有任何操作可以以有意义的方式进一步减少不稳定性。 
3. 将一个立方体从最大的塔移动到最小的塔。 

这会将极端值之间的高度差距至少减少 1，因为一个值会减小，而另一个值会增加。 
4. 将此操作记录为一对索引。 
5. 重复直到达到 k 次操作或无法进行改进。 
6. 最后，将不稳定性重新计算为最大高度减去最小高度，并将该值与操作列表一起输出。 

### 为什么它有效

 关键的不变量是，每次操作都会直接减少当前最大和最小塔之间的差异，除非多个塔达到极端，在这种情况下，在最坏的情况下效果仍然不会恶化。 由于减少不稳定的唯一方法是将质量从较高的塔移动到较低的塔，因此始终选择全局极端值可确保我们永远不会在对最终扩散影响较小的非极端转移上浪费一步。 

因为每次移动都会以局部最优的方式减少潜在的差距，并且该过程受 k 个操作的限制，所以该算法在允许的移动次数内产生尽可能小的不稳定性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

ops = []

for _ in range(k):
    mx_i = 0
    mn_i = 0

    for i in range(n):
        if a[i] > a[mx_i]:
            mx_i = i
        if a[i] < a[mn_i]:
            mn_i = i

    if a[mx_i] - a[mn_i] <= 1:
        break

    a[mx_i] -= 1
    a[mn_i] += 1
    ops.append((mx_i + 1, mn_i + 1))

mx = max(a)
mn = min(a)
print(mx - mn, len(ops))
for i, j in ops:
    print(i, j)
```该实现重复扫描所有塔以找到当前的最大值和最小值。 这是故意简单的，因为 n 足够小，O(nk) 仍然有效。 

一个微妙的细节是停止条件`a[mx_i] - a[mn_i] <= 1`。 一旦差值最多为 1，任何进一步的重新分配都无法在剩余的移动中有意义地减少最终的不稳定性，因为系统在整数约束下已经尽可能平坦。 

另一个细节是我们在每一步重新计算最大值和最小值，而不是维护堆。 这避免了复杂性错误并且在限制下足够快。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(k·n) | k 个操作中的每一个都会扫描 n 个塔以找到最小值和最大值 |
 | 空间| O(n + k) | 存储高度和操作列表 |

 当 n ≤ 100 且 k ≤ 1000 时，最大操作数为 1000，每个操作最多花费 100 次扫描，因此大约有 100k 次原始检查，这在限制内很容易很快。

def run(inp: str) -> str:

    from collections import deque
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    ops = []

    for _ in range(k):
        mx_i = 0
        mn_i = 0
        for i in range(n):
            if a[i] > a[mx_i]:
                mx_i = i

        a[mn_i] += 1
        ops.append((mx_i + 1, mn_i + 1))

    mx = max(a)
    mn = min(a)
    out = [str(mx - mn), str(len(ops))]

        out.append(f"{i} {j}")

 ## 边缘情况

 对于已经统一的塔，算法立即发现 max 减去 min 等于 0，并在记录任何操作之前停止。 用于输入`5 10 / 7 7 7 7 7`，第一次扫描给出相同的最大和最小索引，因此差异条件触发提前终止并输出零不稳定。 

对于k很大但不必要的情况，比如`4 1000 / 1 2 3 4`，一旦范围变为至多 1，算法就会提前停止。这可以防止浪费操作，这些操作只会振荡值而不会改善目标。 

对于高度倾斜的分布，例如`3 5 / 1 100 1`，每次迭代都正确识别单个最高的塔，并重复将其排空至最小值。 当接收器均衡时，该过程会自然地交替接收器，从而保持正确性，而无需手动跟踪目标。
