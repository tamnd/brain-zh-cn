 ## 解决方案
 ## 问题理解

 我们有一个矩形的树木网格。 火灾从多个牢房同时起火，每分钟都会蔓延到共用一侧的相邻牢房。 任务是找到燃烧时间尽可能长的任何单元格，这意味着它比其他所有树都晚着火。 

这实际上是网格上的最短路径问题。 每次移动到相邻单元需要一分钟，因此单元燃烧的时间是从该单元到任何起始火源的最小曼哈顿距离。 我们想要具有最大距离的单元格。 

网格最多可包含 2000 × 2000 = 4,000,000 个单元格。 这个数字足够大，以至于对所有单元进行二次工作都是危险的。 由于最多有 10 个起点，因此扫描网格一次或执行标准图遍历的解决方案是现实的，但任何涉及重复全网格遍历的解决方案都会很困难。 

一个常见的错误是使用 BFS 分别计算每个源的距离并不断重新开始遍历。 在 400 万个单元网格上，即使是单个 BFS 也已经触及数百万个状态。 这样做 10 次的成本是不必要的。 

另一个微妙的问题是领带处理。 该问题允许任何有效的最远单元格。 假设输入是：```
2 2
1
1 1
```细胞`(1,2)`,`(2,1)`， 和`(2,2)`不要同时燃烧。 最远的一个是`(2,2)`距离为 2。在遍历期间不正确地更新答案的粗心实现可能会意外返回非最远的单元格。 

当存在多个火源时，会出现不同的边缘情况：```
5 5
2
1 1 5 5
```中心细胞最后燃烧，因为每个角落源很快到达附近的细胞。 如果我们仅错误地测量距第一个火源的距离，我们将完全错过第二次火灾的影响。 

尽可能最小的网格也很重要：```
1 1
1
1 1
```唯一的细胞已经在时间 0 燃烧，所以答案一定是`(1,1)`。 索引或边界检查不正确的实现通常会失败。 

## 方法

 最直接的想法就是暴力。 对于网格中的每个单元格，计算其到每个起始火源的曼哈顿距离，保留这些距离中的最小值，然后跟踪具有最大最小距离的单元格。 

对于一个细胞`(x,y)`和来源`(sx,sy)`，燃烧时间为：$$|x - sx| + |y - sy|$$由于最多有 10 个源，因此每个单元的计算成本都很低。 总工作量变为：$$N \times M \times K$$在最坏的情况下：$$2000 \times 2000 \times 10 = 40,000,000$$Python 中四千万个简单的整数运算实际上是可以接受的，只要仔细实现即可。 这就是为什么许多公认的解决方案直接使用暴力。 

尽管如此，这个问题仍被标记为最短路径，因为传播过程本身自然地被建模为多源 BFS。 我们没有明确计算曼哈顿距离，而是逐层模拟火灾扩展。 

关键的观察结果是，当所有源最初插入 BFS 队列时，我们第一次到达某个单元时恰好是火灾到达该单元的最早分钟。 BFS 按距离递增的顺序处理状态，因此最后处理的单元是最后燃烧的单元之一。 

这将问题转换为未加权网格图上的标准最短路径计算。 每条边的成本为 1，多源 BFS 自动计算距最近源的最小距离。 

与暴力距离扫描相比，BFS 避免了重复重新计算距离。 每个单元格都被访问一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N × M × K) | O(1) | O(1) | 已接受 |
 | 最佳 | O(N × M) | O(N × M) | 已接受 |

 ## 算法演练

 1. 阅读网格尺寸和初始火源列表。 
2. 创建大小为访问过的矩阵`N × M`。 一旦火到达某个牢房，它就会被访问。 
3. 在启动 BFS 之前将所有火源推入队列。 

这是关键的多源步骤。 BFS 现在将从每场火灾同时向外扩展，与问题中描述的蔓延过程完全匹配。 
4. 将所有源单元格标记为已访问。 
5. 重复从队列中弹出一个单元格。 
6. 将当前单元格存储为最新处理的位置。 

BFS 按非递减距离顺序处理单元。 因此，较晚弹出的单元格永远不会比较早弹出的单元格更近。 
7. 尝试沿四个网格方向移动。 
8. 对于每个有效的未访问邻居，将其标记为已访问并将其推入队列。 
9. 当 BFS 完成时，输出最后处理的单元。 

该牢房距最近火源的距离最大。 

### 为什么它有效

 未加权图上的 BFS 总是以最短路径距离递增的顺序发现节点。 同时从所有火源出发意味着最近的火源首先到达每个单元格。 队列逐层展开，每一层对应一分钟的火势蔓延。 

由于这种排序，从队列中删除的最终单元属于最远的 BFS 层，这意味着它到任何源的最小距离都是最大的。 返回该单元格是正确的。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

# solution

def solve():
    n, m = map(int, input().split())

    k = int(input())
    arr = list(map(int, input().split()))

    visited = [[False] * m for _ in range(n)]
    q = deque()

    for i in range(0, 2 * k, 2):
        x = arr[i] - 1
        y = arr[i + 1] - 1

        visited[x][y] = True
        q.append((x, y))

    directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

    last_x, last_y = 0, 0

    while q:
        x, y = q.popleft()

        last_x, last_y = x, y

        for dx, dy in directions:
            nx = x + dx
            ny = y + dy

            if 0 <= nx < n and 0 <= ny < m and not visited[nx][ny]:
                visited[nx][ny] = True
                q.append((nx, ny))

    print(last_x + 1, last_y + 1)

solve()
```队列最初包含每棵燃烧的树。 这就是使它成为多源 BFS 而不是来自单个节点的普通 BFS 的原因。 

这`visited`基质防止重新访问细胞。 如果没有它，同一个单元格可以从不同的方向插入多次，这将大大增加运行时间。 

读取输入后，坐标立即转换为基于 0 的索引。 这使得边界检查变得简单，因为 Python 列表是从 0 索引的。 在打印之前，答案将转换回从 1 开始的索引。 

变量`last_x, last_y`每次从队列中弹出单元格时都会更新。 由于 BFS 按距离递增的顺序处理单元格，因此最终弹出的单元格是最远的单元格之一。 

方向的顺序并不重要，因为问题允许任何有效的答案。 

## 工作示例

 ### 示例 1

 输入：```
3 3
1
2 2
```火从中心开始。 

| 步骤| 队列前面 | 新添加的单元 | 最后处理 |
 | --- | --- | --- | --- |
 | 1 | (2,2) | (1,2)、(3,2)、(2,1)、(2,3) | (2,2) |
 | 2 | (1,2) | (1,1), (1,3) | (1,1), (1,3) | (1,2) |
 | 3 | (3,2) | (3,1), (3,3) | (3,1), (3,3) | (3,2) |
 | 4 | 剩余边缘单元| 无 | 变化 |
 | 决赛| (3,3) | 无 | (3,3) |

 一个有效的答案是`(3,3)`。 样本输出`(1,1)`因为几个角都与最大距离相关。 

该轨迹显示了 BFS 如何分层扩展。 距离 1 处的所有单元格都会先于距离 2 处的任何单元格进行处理。

 ## 边缘情况

 考虑尽可能最小的输入：```
1 1
1
1 1
```队列最初仅包含`(1,1)`。 BFS 立即将其弹出，并且不存在邻居。 算法输出`(1,1)`，这是正确的，因为唯一的树已经在燃烧。 

现在考虑多个相互竞争的火源：```
5 5
2
1 1 5 5
```最初，两个角落都进入队列。 BFS 同时向外扩展。 中心细胞`(3,3)`比任何其他单元格都晚到达，因为两场火都需要四个步骤才能到达它。 由于 BFS 总是首先处理较小的距离，`(3,3)`出现在最后一层并成为答案。 

领带盒也很有趣：```
3 3
1
2 2
```所有四个角距中心源的距离相等。 BFS 可能会根据队列顺序完成其中任何一个。 该问题明确允许任何有效答案，因此这种行为是正确的。 

最后，考虑一个窄网格：```
1 5
1
1 3
```火势仅向左和右蔓延。 BFS 正确处理了这个问题，因为移动检查独立地使用行和列的边界。 最远的细胞是`(1,1)`和`(1,5)`，并且任一答案均被接受。
