 ## 解决方案
 ## 问题理解

 我们将三个杯子排成一排，一个球从其中一个杯子的下方开始。 表演者恰好执行了三次交换。 每次交换交换两个杯子的位置。 所有交换完成后，我们必须确定哪个杯子包含球。 

输入首先给出起始杯子索引，从 1 到 3。然后是三行，每行包含两个整数，表示在洗牌期间交换的杯子。 

关键细节是，球仅在当前杯子参与交换时才会移动。 如果球位于 2 号杯下方，而我们交换 1 号杯和 3 号杯，则球会留在 2 号杯下方，因为它的杯子从未移动。 

限制很小。 总是有正好三个杯子和正好三个交换。 即使是可以想象的最慢的实现也会立即运行。 这意味着问题纯粹是正确模拟过程而不犯逻辑错误。 

错误的主要来源是误解交换的含义。 

考虑这个输入：```
1
2 3
2 3
2 3
```球从 1 号杯下方开始。所有交换都不涉及 1 号杯，所以答案仍然是：```
1
```如果不小心，每一步都盲目地改变位置，可能会错误地移动球。 

当同一个交换出现多次时，会发生另一种微妙的情况：```
2
1 2
1 2
1 2
```第一次交换后，球从 2 号杯移动到 1 号杯。 

第二个之后，返回到第 2 杯。 

第三次之后，它会移回第 1 杯。 

正确的输出是：```
1
```一个只记住杯子是否被交换过的有缺陷的解决方案在这里会失败，因为交换必须按顺序处理。 

另一个容易犯的错误是忘记交换是对称的。 如果球位于第 3 杯下方并且洗牌是`1 3`，球必须移动到杯子 1。```
3
1 3
1 2
2 3
```正确的模拟给出：```
2
```如果实现仅检查当前位置是否等于该对中的第一个数字，则它将错过当前杯子等于第二个数字的交换。 

## 方法

 最直接的想法就是完全按照描述来模拟游戏。 我们存储当前包含球的杯子。 每次洗牌时，我们都会检查两个交换的杯子。 

如果球位于第一个杯子下方，它将移动到第二个杯子。 

如果球位于第二个杯子下方，则它会移动到第一个杯子。 

否则什么都不会改变。 

这种强力模拟已经完全可以接受，因为问题的规模是恒定的。 我们只处理三次交换，因此操作总数很少。 

另一种可能的强力解释是在数组中明确跟踪所有三个杯子，并在每一步物理交换它们的内容。 这也有效，但它存储的信息超出了必要的范围。 我们只关心一件事，即球的当前位置。 

关键的观察是游戏的整个状态可以用单个整数表示。 由于只有一个杯子包含球，因此我们不需要单独为空杯子建模。 每次洗牌要么改变这个整数，要么保持不变。 

这将问题简化为具有恒定内存和恒定时间的紧凑状态转换过程。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 全罩杯模拟| O(3) | O(3) | 已接受 |
 | 仅跟踪球位置 | O(3) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取球开始处的初始杯指数。 
2. 将此索引存储在名为的变量中`pos`。 该变量始终代表球的当前位置。 
3. 将三个交换一一处理。 
4. 对于每次交换`(a, b)`，检查球是否位于这些杯子之一的下方。 

如果`pos == a`， 放`pos = b`因为球与杯子一起移动`a`。 
5. 否则，如果`pos == b`， 放`pos = a`。 

交换在两个方向上进行，因此球从`b`到`a`在这种情况下。 
6.如果`pos`都不匹配`a`也不`b`，什么也不做。 

洗过的杯子里没有球。 
7. 全部3次交换后，打印`pos`。 

### 为什么它有效

 不变量很简单：在每次处理后的洗牌之后，`pos`等于当前包含球的真实杯子。 

最初这是真的，因为`pos`从输入设置。 在洗牌过程中，正好有两个杯子交换位置。 如果球位于其中一个杯子的下方，它就会移动到另一个杯子。 如果没有，它的位置不会改变。 更新规则准确地反映了这些物理运动，因此每一步之后不变式仍然成立。 第三次洗牌后，`pos`是最终的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

pos = int(input())

for _ in range(3):
    a, b = map(int, input().split())

    if pos == a:
        pos = b
    elif pos == b:
        pos = a

print(pos)
```该程序仅存储球的当前位置。 这与我们永远不需要跟踪空杯子的观察结果相符。 

该循环恰好运行了三次，因为该问题保证了三次洗牌。 对于每次交换，我们都会将当前球的位置与两个交换的杯子进行比较。 

条件的顺序稍有影响。 一旦球匹配`a`，我们立即将其移至`b`。 使用`elif`防止在同一迭代中意外地再次检查更新的值。 

不需要数组索引，因此不存在差一风险。 直接使用输入中给出的杯数。

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    pos = int(input())

    for _ in range(3):
        a, b = map(int, input().split())

        if pos == a:
            pos = b
        elif pos == b:
            pos = a

    print(pos)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("1\n1 2\n2 1\n2 1\n") == "2\n", "sample 1"

# minimum movement, ball never touched
assert run("1\n2 3\n2 3\n2 3\n") == "1\n", "ball never moves"

# repeated swaps
assert run("2\n1 2\n1 2\n1 2\n") == "1\n", "odd number of repeated swaps"

# ball starts at highest index
assert run("3\n1 3\n1 2\n2 3\n") == "1\n", "swap symmetry"

# every swap affects the ball
assert run("2\n2 3\n1 3\n1 2\n") == "2\n", "continuous movement"

 ## 边缘情况

 考虑球从未参与任何交换的情况：```
1
2 3
2 3
2 3
```该算法开始于`pos = 1`。 

对于每次洗牌，两个端点都不等于`1`，所以该值永远不会改变。 

状态跟踪：```
1 -> 1 -> 1 -> 1
```最终答案正确打印为`1`。 

现在考虑同一对的重复交换：```
2
1 2
1 2
1 2
```执行过程如下：

 第一次交换：`2 -> 1`第二次交换：`1 -> 2`第三次交换：`2 -> 1`最终结果：```
1
```这证实了该算法尊重顺序并独立处理每个洗牌。 

最后，考虑当前位置与交换的第二个值匹配的情况：```
3
1 3
1 2
2 3
```第一次洗牌是`(1, 3)`。 自从`pos == 3`，算法进入第二个条件并更新`pos = 1`。 

完整的轨迹变为：```
3 -> 1 -> 1 -> 1
```最终的答案是`1`。 这验证了双向的交换处理是否正确。
