 ## 解决方案
 ## 问题理解

 我们有一系列的剑，每把剑都有一个强度值，还有一系列的怪物，每一个都需要一定次数的攻击才能被击败。 每把剑最多可以使用一次，因为击中怪物后它会立即断裂。 

在开始游戏之前，我们选择一个阈值$x$。 至少有力量的剑$x$可用； 所有较弱的剑都被完全忽略。 带着可用的剑，我们一层一层地前进，一层一层地$i$我们必须花费$b_i$不同的剑来击败那个怪物。 一旦我们用完可用的剑，我们就会停止在当前水平。 

分数计算如下$x \times (\text{number of fully completed levels})$。 目标是选择$x$最大化这个分数。 

关键结构是增加$x$减少可用剑的数量，但增加乘数。 这种权衡在某种程度上是单调的，暗示着排序和前缀推理。 

约束允许最多$2 \cdot 10^5$全部的$n$，所以任何解决方案$O(n^2)$per test is immediately impossible. 甚至$O(n \log n)$必须谨慎使用，并且对所有不同剑强度的任何每值模拟都必须简化为线性或近线性摊销行为。 

天真的尝试可能会尝试一切可能$x$从所有的集合$a_i$，每次模拟游戏，计算可以完成多少关。 这将需要最多$O(n)$每个候选人的模拟和$O(n)$候选人，导致$O(n^2)$总体而言，这太慢了。 

一个更微妙的失败案例来自于没有对剑进行排序的贪婪模拟。 例如，如果不优先考虑更强的剑，天真的分配可能会提前浪费它们并低估给定阈值的可实现水平。 

当所有剑都相同时会出现另一种边缘情况。 那么答案纯粹由前缀和决定$b_i$，以及任何对“严格小于$x$” vs “至少$x$” 会导致可用计数出现相差一的错误。

 ## 方法

 蛮力的想法很简单：选择一个候选难度$x$, 过滤所有剑的强度至少$x$，然后模拟逐级消耗剑。 每级消耗$b_i$剑，所以我们递减计数器，直到我们无法继续前进。 这是正确的，因为它直接反映了游戏规则。 

问题是成本。 如果我们尝试所有可能的值$x$, 最多有$n$独特的剑力。 对于每一个，过滤成本$O(n)$，并且模拟关卡需要花费另一笔费用$O(n)$。 这导致$O(n^2)$最坏情况下的每个测试用例。 

关键的观察是对于固定的$x$，只有可用剑的数量才重要，而不是它们的身份。 一旦我们按照力量降序对剑进行排序，增加$x$对应于逐渐激活此排序数组的前缀。 我们可以从高到低扫描阈值并维护可用的剑数量，而不是从头开始重新计算。 

第二个重要的想法是，在给定固定数量的可用剑的情况下，如何计算我们可以完成的关卡数量。 由于级别是连续的并且每个级别都会消耗$b_i$资源，我们预先计算前缀和$b$。 完成的关卡数是最大的索引$k$这样$\sum_{i=1}^k b_i \leq \text{available swords}$。 

这将每次评估减少为对前缀和的二分搜索，或者更好的是，我们可以预先计算每个可能的剑数的最大可达级别一次，并在概念上重用它，同时扫荡优势。 

最后，我们将每个阈值的分数评估为：$$\text{score} = (\text{current threshold}) \times (\text{max levels achievable with available swords})$$| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(n)$| 太慢了 |
 | 最佳 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1.按照剑的强度降序排列。 这让我们可以解释选择阈值$x$作为选择此排序列表的前缀。 前缀长度直接给出了可用剑的数量。 
2. 计算怪物需求的前缀和$b_i$。 这使我们能够快速确定使用给定数量的剑可以完成多少个级别。 
3. 对于每个可能的前缀长度$k$（这意味着我们使用顶部$k$最强的剑），确定与其相关的最佳阈值。 自然的选择是该前缀中最小的剑，因为那是最大的$x$仍然包括所有$k$剑。 
4. 对于每个$k$，计算可以完成多少个级别。 这是最大的索引$i$使得 prefix_sum[i] ≤ k。 这可以通过二分查找找到。 
5. 将候选人分数计算为$x \cdot \text{levels}$，并跟踪所有最大值$k$。 

这样做的原因是，只有当我们包含或排除剑时，最佳阈值才会改变。 在两个连续的不同剑强度之间，可用剑的集合不会改变，因此检查中间值$x$是不必要的。 

### 为什么它有效

 对于任何固定阈值$x$，这组可用的剑正是那些带有$a_i \ge x$。 在产生相同可用集的所有阈值中，增加$x$在不改变可行性的情况下提高分数。 因此最优选择为$x$总是等于一些剑力。 这会将搜索空间从连续值折叠到最多$n$候选者，并且每个候选者都完全由排序优势的前缀来表征。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from bisect import bisect_right

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort(reverse=True)
        
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + b[i]
        
        # precompute max level for k swords via binary search on prefix sums
        best = 0
        
        for k in range(1, n + 1):
            x = a[k - 1]
            # max levels with k swords
            levels = bisect_right(pref, k) - 1
            best = max(best, x * levels)
        
        print(best)

if __name__ == "__main__":
    solve()
```该解决方案首先对剑的强度进行排序，以便每个前缀对应于某个阈值下可用剑的有效选择。 前缀总和超过$b_i$允许从“可用剑的数量”到“可以清除多少个级别”的快速转换。 

二分查找步骤很微妙：`bisect_right(pref, k) - 1`返回总要求不超过的最大级别数$k$。 这避免了模拟逐级消耗。 

一个常见的错误是颠倒前缀索引的含义：前缀和数组在开头包含一个零，因此必须小心地偏移级别计数。 另一个错误是忘记每个测试用例都需要独立的前缀重新计算。

 ## 边缘情况

 一把剑的最小案例表明，如果唯一一把剑的强度低于任何有用的阈值，则答案会崩溃为零，因为无法完成任何级别。 该算法处理这个问题是因为$k=1$，根据前缀和计算的级别为零，因此无论如何，分数都保持为零$x$。 

一个案例，所有$b_i = 1$强调前缀逻辑。 每多一把剑都会直接转化为一个更高的等级，因此最好的分数往往来自于平衡大$x$有足够的前缀长度。 对前缀和的二分搜索可以正确捕获这种线性累加，无需模拟。 

混合强度案例测试排序是否正确对齐阈值解释。 由于阈值与排序前缀相关，因此原始顺序和排序顺序之间的任何不匹配都会产生不正确的级别计数。 该算法通过完全分离两个域来避免这种情况：$a$已排序，$b$保持原始级别顺序，并且只有前缀和$b$被使用。
