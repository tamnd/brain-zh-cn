 ## 解决方案
 ## 问题理解

 我们得到一个整数数组和一个固定的增量值。 一步操作中，我们可以选择数组中的任意位置，并每次将该单个元素增加完全相同的数量。 我们可以对任何索引重复此操作任意多次。 问题是我们是否可以转换数组，使其总和恰好等于目标值。 

关键是我们不重新排列元素或减去值。 每个操作严格地将总和增加固定步长，因为每个操作添加相同的值$x$恰好是一个元素。 所以总和以一种非常受控的算术方式演变。 

限制很小：$n \le 10$,$x \le 10$， 和$s \le 100$。 这立即消除了对性能复杂性的任何担忧。 即使对状态进行强力探索原则上也是可行的，但问题的结构表明直接算术条件将充分表征可达性。 

当当前总和已经超过目标时，就会出现一种微妙的情况。 由于每次操作只会增加总和，因此任何此类情况都是不可能的。 另一种边缘情况是目标总和与当前总和之间的差异与大小增量不兼容时$x$。 例如，如果差值不能被整除$x$，没有任何操作序列可以准确地落在目标上。 

## 方法

 思考问题的强力方法是模拟操作。 从初始数组开始，我们重复尝试所有可能的索引增量并跟踪所有可达的总和。 由于每次移动都会使总和精确增加$x$，这很快就变得不必要了：唯一重要的状态是当前总和，而不是值的分布。 

关键的观察是每个操作都会精确地改变总和$x$，无论选择哪个索引。 这将整个问题分解为单变量可达性条件。 如果初始总和是$S_0$，然后之后$k$运算总和变为$S_0 + kx$。 问题简化为检查是否存在非负整数$k$这样：$$S_0 + kx = s$$这相当于检查$s \ge S_0$和$s - S_0$可以整除$x$。 

数组的进一步结构并不重要。

 ## 算法演练

 1. 计算数组的初始和。 这表示任何操作之前总和的最小可能值。 
2. 将此总和与目标值进行比较$s$。 如果初始总和已经大于$s$，没有任何操作可以减少它，所以答案立即是“NO”。 
3. 计算差异$d = s - S_0$。 这是达到目标所需的增加总量。 
4. 检查是否$d$可以整除$x$。 每个操作都贡献准确$x$，所以只有$x$是可达的。 
5. 如果两个条件都成立，则输出“YES”，否则输出“NO”。 

### 为什么它有效

 总和完全取决于执行的操作数量，而不是应用它们的位置。 每个操作都精确地相加$x$到全局总和，因此可达总和形成一个算术级数，从初始总和开始，步长为$x$。 任何索引选择序列都不能打破这种结构，这使得整除$x$既必要又充分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, s, x = map(int, input().split())
        a = list(map(int, input().split()))
        
        total = sum(a)
        
        if total > s:
            print("NO")
            continue
        
        diff = s - total
        
        if diff % x == 0:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```实现直接遵循导出条件。 第一个重要的步骤是计算每个测试用例一次的总和。 这是安全的，因为$n \le 10$。 金额超过时提前退出$s$避免不必要的算术检查，尽管它不是正确性所必需的。 

可除性检查捕获了每个操作都以固定增量更改总和的事实。 无需模拟选择哪些指数。

 | 步骤| 总和 |

 我们检查可行性：

 -$6 \le 8$-$8 - 6 = 2$，可除以$x = 2$所以答案是“是”。 

这显示了一种只需要一次操作的情况，并且它可以应用于任何索引。

 ## 边缘情况

 当初始总和已经超过目标时，算法立即返回“NO”。 例如，如果数组是`[5, 5]`,$x = 1$， 和$s = 9$，总和为 10，已经大于 9。由于所有操作仅增加值，因此没有序列可以将其降低，并且早期检查正确地拒绝它。 

当差值不能被整除时$x$，该算法正确地阻止了不可能的转换。 例如，使用数组`[1, 1, 1, 1]`,$x = 2$， 和$s = 7$，初始总和为 4。差值为 3，并且由于每个操作都会以 2 为步长更改总和，因此任何操作组合都无法精确达到 7。
