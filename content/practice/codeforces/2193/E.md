 ## 解决方案
 ## 问题理解

 我们得到一个数组，其值介于`1`和`n`。 一个元素可以重复使用任意多次，因此唯一重要的是数组中存在哪些值，而不是它们出现了多少次。 

对于每个整数`i`从`1`到`n`，我们必须找到最小数量的所选数组值，其乘积恰好为`i`。 如果不能形成这样的产品，我们输出`-1`。 

查看问题的一个有用方法是将其视为乘法图。 如果一个值`k`出现在数组中，然后来自产品`x`我们可能会搬到`x * k`，前提是结果不超过`n`。 每一次乘法都使用一个以上选定的元素。 

总和为`n`所有测试用例最多是`3 · 10^5`。 任何接近的解决方案`O(n^2)`立即被排除。 我们周围需要一些东西`O(n log n)`跨测试用例。 

一些边缘情况很容易被错误处理。 

考虑：```
n = 3
a = [1, 1, 1]
```产品`1`可以通过一个选定的元素获得，因此答案为`1`是`1`， 不是`0`。 该语句要求至少选择一个元素。 

考虑：```
n = 4
a = [2]
```产品`4`可获得为`2 · 2`，即使数组只包含一次`2`。 允许重复使用。 

考虑：```
n = 5
a = [2, 4]
```产品`3`是不可能的。 粗心的 DP 假设每个数字都可以由较小的数字构建，因此会错误地将其标记为可达。 

## 方法

 蛮力的想法是将每个产品视为一个状态并运行最短路径搜索。 从产品来看`x`，尝试乘以每个可用的数组值。 这是正确的，因为每次乘法都对应于选择一个或多个元素。 

问题在于转换的数量。 如果有`Θ(n)`不同的可用值，我们检查每个状态的所有值，复杂性变成`Θ(n^2)`，对于`n = 3 · 10^5`。 

关键的观察是所有产品最多`n`，并且每个过渡都有形式```
x -> x * k
```在哪里`k`是数组中存在的值。 

自从`k ≥ 2`对于每个有用的乘法，目标都严格大于源。 该图是一个 DAG，其拓扑顺序只是递增的数字顺序。 

让`dp[x]`是获得产品所需的最小选定元素数`x`，假设我们从中性产品开始`1`有成本`0`。 

当我们处理`x`, 每个可用的乘数`k`产生松弛：```
dp[x * k] = min(dp[x * k], dp[x] + 1)
```我们不是迭代每个状态的所有可用值，而是迭代所有可能的乘数`k`最多`n / x`并简单地检查是否`k`存在于数组中。 

检查对的总数是```
Σ floor(n / x)
```这是`O(n log n)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 构建布尔数组`present`， 在哪里`present[v]`如果值则为真`v`出现在数组中。 
2. 创建一个初始化为无穷大的 DP 数组。 
3. 设置`dp[1] = 0`。 这代表选择任何元素之前的空产品。 
4. 进程号`x`从`1`到`n`按递增顺序。 
5.如果`dp[x]`仍然是无穷大，跳过它，因为乘积`x`无法形成。 
6. 对于每个乘数`k`从`2`到`⌊n / x⌋`：

如果`present[k]`是真的，放松```
dp[x * k] = min(dp[x * k], dp[x] + 1)
```乘以`k`对应于选择一个附加数组元素。 
7. 建立答案。 

为了`i > 1`，答案是`dp[i]`如果它是有限的，否则`-1`。 

为了`i = 1`，答案是：```
1  if present[1]
-1 otherwise
```我们无法输出`0`因为至少必须选择一个元素。 

### 为什么它有效

 该图包含一条边`x`到`x * k`每当值`k`存在于数组中。 每条边线都有成本`1`，每条边都指向一个更大的节点。 因此，增加数字顺序是有效的拓扑顺序。 

加工时`x`,`dp[x]`已经等于产品的最短路径长度`1`到`x`。 放宽所有传出边缘可将最优值传播到更大的产品。 由于每条路径完全对应于所选数组元素的序列，`dp[i]`成为其乘积为的最小选定元素数`i`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        present = [False] * (n + 1)
        for x in a:
            present[x] = True

        INF = 10 ** 9
        dp = [INF] * (n + 1)
        dp[1] = 0

        for x in range(1, n + 1):
            if dp[x] == INF:
                continue

            limit = n // x
            for k in range(2, limit + 1):
                if present[k]:
                    nx = x * k
                    if dp[nx] > dp[x] + 1:
                        dp[nx] = dp[x] + 1

        ans = []

        if present[1]:
            ans.append("1")
        else:
            ans.append("-1")

        for i in range(2, n + 1):
            if dp[i] == INF:
                ans.append("-1")
            else:
                ans.append(str(dp[i]))

        print(" ".join(ans))

solve()
```这`present`数组删除所有重复值。 由于元素可以无限次地重复使用，因此只有存在才重要。 

DP从产品开始`1`有成本`0`。 这是一个虚拟的起始状态，本身并不是一个有效的答案。 这就是为什么产品的答案`1`是分开处理的。 

循环顺序至关重要。 加工`x`递增顺序有效，因为每次转换都会达到更大的数字。 无需优先队列或重复放松。 

另一个微妙的点是乘数从`2`。 乘以`1`永远不会改变产品并且会产生自循环。 这种转换对于最短路径来说是无用的，可以忽略。

 ## 边缘情况

 考虑：```
1
3
1 1 1
```DP保留`dp[1] = 0`，但产品的最终答案`1`不是从 DP 获取的。 算法检查`present[1]`和输出`1`，满足至少必须选择一个元素的要求。 

考虑：```
1
4
2 2 2 2
```加工`x = 1`创造`dp[2] = 1`。 后来处理`x = 2`创造`dp[4] = 2`。 该算法正确地允许重复使用相同的值，即使数组中只存在一次。 

考虑：```
1
5
2 4 4 2 2
```任何过渡都无法达到`3`或者`5`。 它们的 DP 值保持无穷大，因此算法输出`-1`对于两个目标。 这可以防止无法访问的产品被标记为有效。
