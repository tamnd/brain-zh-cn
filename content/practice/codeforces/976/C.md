 ## 解决方案
 ## 问题理解

 我们在数轴上得到了闭区间的集合。 每个区间代表一个具有左端点和右端点的线段，我们需要确定是否存在一对不同的线段，使得一个线段完全包含在另一个线段内。 

形式上，对于两个段$[l_i, r_i]$和$[l_j, r_j]$，我们想要找到索引$i \neq j$这样$l_i \ge l_j$和$r_i \le r_j$。 如果存在这样的对，我们返回任何有效嵌套对的索引； 否则我们会报告不存在嵌套。 

约束允许最多$3 \cdot 10^5$段和端点可以大到$10^9$。 这立即排除了任何二次比较策略。 一个天真的$O(n^2)$扫描将执行大约$9 \cdot 10^{10}$最坏情况下的比较，远远超出了两秒内可以执行的范围。 

关键的困难在于遏制同时取决于两个维度。 仅按一个坐标排序不会自动保留另一个坐标，因此粗心的排序可能会隐藏有效答案。 

一些边缘情况说明了常见的陷阱。 如果所有段都相同，则任何一对都是有效的并且必须被检测； 仅寻找严格不平等的解决方案可能会错误地忽略这一点。 如果段在两个端点都严格增加，例如$[1,2], [2,3], [3,4]$，即使间隔以结构化方式重叠，也没有包含。 另一个棘手的情况是当一个段非常长并且包含许多其他段时，例如$[1,100]$含有$[2,99]$,$[3,98]$， 等等。 除非重新组织结构，否则仅按原始顺序比较邻居的算法将在这里失败。 

## 方法

 强力方法检查每对段并验证其中一个是否包含另一个。 这很简单：对于每个$i$, 与所有的进行比较$j > i$并测试遏制条件。 这是正确的，因为它明确地评估所有可能的对，但其成本呈二次方增长。 和$3 \cdot 10^5$细分，比较的数量变得令人望而却步，即使优化的常数因子也无法挽救它。 

关键的观察结果是，如果我们将问题简化为精心选择的顺序，那么遏制就会变得更容易检测。 如果我们按段的左端点升序对段进行排序，则任何潜在的容器都必须出现在该排序中的较早位置或相同位置。 然而，这仍然是不够的，因为在具有相同左端点的线段中，具有较大右端点的线段应被视为外部线段。 

这会产生更精确的结构：按左端点升序排序，对于关系，按右端点降序排序。 一旦按照这个顺序，每当我们扫描列表时，任何较早开始或在同一点开始并较晚结束的段都是所有后续段的潜在容器。 

然后，我们在扫描时维护迄今为止看到的最佳（最大右端点）段。 如果当前段在此最大值或之前结束，则它包含在先前看到的段中。 否则，它成为新的候选容器。 

这将二维比较问题转化为具有保持不变性的单遍问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了 |
 | 带跟踪的排序扫描 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将问题转化为在扫描排序列表时检测包含关系。 

1.为所有段附加索引，以便我们可以在排序后返回原始位置。 这是必要的，因为排序会破坏输入顺序。 
2. 通过增加左端点对段进行排序。 如果两个线段共享相同的左端点，则按右端点递减排序。 这种排序确保了对于相等的开始，最宽的间隔排在第一位，这是唯一可以包含具有相同左边界的其他间隔的间隔。 
3. 初始化两个变量：一个用于存储迄今为止看到的最大右端点，另一个用于存储哪个段达到了该最大值。 
4. 从左到右迭代排序的段。 对于每个段$[l, r]$，将其右端点与当前最大右端点进行比较。 
5. 如果$r \le \text{maxR}$，那么该段完全包含在产生的段中$\text{maxR}$，因为该段开始时间不晚，并且至少延伸到最右侧。 
6. 如果没有找到包含，并且当前段的右端点大于$\text{maxR}$，将存储的最佳段更新为此段。 

关键的推理步骤是，一旦我们确保排序顺序，唯一缺少的遏制条件就是右端点比较，因为左端点条件已经由排序隐式强制执行。 

### 为什么它有效

 在扫描的每一步中，存储为在所有先前看到的段中具有最大右端点的段保证是任何未来段的有效候选容器，因为它在具有最大向右范围的那些段中具有最小的可能左端点。 任何未通过遏制测试的段都必须比所有先前的段更向右延伸，在这种情况下，它成为新的最佳候选者。 这个不变量确保如果包含对存在，当我们遇到内部段时，它将被准确地检测到。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
segs = []

for i in range(n):
    l, r = map(int, input().split())
    segs.append((l, r, i + 1))

segs.sort(key=lambda x: (x[0], -x[1]))

best_r = -1
best_idx = -1

for l, r, idx in segs:
    if r <= best_r:
        print(idx, best_idx)
        sys.exit(0)
    if r > best_r:
        best_r = r
        best_idx = idx

print(-1, -1)
```该解决方案首先保留原始索引，因为排序会改变顺序，但输出必须引用输入位置。 排序步骤是一种结构转换，可在单次传递中检测到遏制。 

在扫描过程中，`best_r`表示迄今为止在潜在容器的段中看到的最右端点。 如果我们找到右端点不超过该值的线段，则它必须被较早的线段完全覆盖，因为由于排序，较早的线段的左端点也小于或等于当前的线段。 

提前退出是安全的，因为一旦找到有效的对，任何对都是可以接受的。

 ## 边缘情况

 一种微妙的情况是多个线段共享相同的左端点。 例如：```
3
1 10
1 5
1 7
```按右端点在相等的左端点内降序排序后，线段 (1,10) 首先出现。 随着扫描的进行，`best_r`立即变为 10，并且所有其他都被正确检测为包含。 如果没有二次排序，较短的片段可能会错误地成为“最佳”片段并阻止检测。 

另一种情况涉及严格增加间隔：```
3
1 2
2 3
3 4
```这里，`best_r`总是增加，并且没有任何细分能够满足`r <= best_r`在一个有意义的时刻。 算法正确到达末尾并返回`-1 -1`，反映了遏制的缺失。
