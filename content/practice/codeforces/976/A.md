 ## 解决方案
 ## 问题理解

 我们得到一个已经处于有效规范形式的二进制字符串，这意味着它表示二进制的非负整数，没有不必要的前导零。 任务是使用两种允许的操作将该字符串转换为二进制比较规则下的最小可能值：自由交换相邻字符以及通过用单个“1”替换“11”来减少连续字符的出现。 

第一个操作使我们能够完全自由地重新排列字符，因为任何排列都可以通过重复相邻交换来实现。 第二个操作通过压缩 1 对来改变字符串的结构，有效地减少字符串中 1 的数量。 

输出不仅仅是任何重新排列的字符串，而是在这些转换下可以获得的按字典顺序最小的二进制字符串，同时仍然保留不带前导零的有效表示形式。 

约束 n ≤ 100 意味着即使二次推理或小型模拟也是可行的，但操作的结构表明我们不应该盲目模拟。 相反，我们应该确定不变的量，特别是可以有效地减少和重新排列多少个零和一。 

简单的方法会尝试所有排列和约简，但即使对于 n = 100，这也是一个天文数字。 即使是重复应用没有结构不变量的操作的贪婪模拟也可能会失败。 

当字符串仅包含 1 时，会出现微妙的边缘情况。 例如，输入“111”可以重复折叠为“1”，并且任何将缩减视为单遍的方法都会错误地停止在“11”。 另一种情况是当零分开时，例如“10101”，其中重新排列以非局部方式与压缩相互作用。 天真的贪婪交换策略可能无法意识到首先将它们组合在一起可以最大化压缩。 

## 方法

 蛮力的想法是以所有可能的方式重复应用这两个操作，跟踪所有可达的字符串，并选择最小值。 这是可行的，因为状态空间是有限的并且所有转换都是有效的。 然而，每次交换都会显着扩展分支因子，即使 n 很小，通过交换和压缩的交错可到达的不同二进制字符串的数量也会呈指数增长。 瓶颈在于交换生成所有排列，而压缩动态改变字符串长度，使得状态上的 BFS 或 DFS 不可行。 

关键的观察是交换允许任意重新排序，因此最终结果仅取决于零和一的计数，而不取决于它们的原始位置。 压缩规则“11 → 1”意味着多个 1 会折叠成一个，因此任何正数的 1 最终都会表现得像一个。 因此，唯一有意义的区别是是否至少有一个“1”或根本没有，以及零相对于最后一个“1”的排列方式。 

如果没有“1”，则答案就是“0”。 如果至少有一个“1”，那么所有的“1”都可以合并为一个“1”，然后我们只需要最优地放置零即可。 由于不允许使用前导零，因此最小的安排是将单个“1”尽可能放置在左侧，同时在其后面保留零，从而生成“1”形式的字符串，后跟全零。 

因此，问题就简化为计算“1”是否存在以及计算“0”。

 ## 算法演练

1. 扫描字符串并统计有多少个零以及是否存在至少一个“1”。 这捕获了任意交换后的所有相关信息。 
2. 如果不存在‘1’，则返回“0”，因为任何全零的字符串都代表零并且不能进一步减少。 
3. 如果至少存在一个“1”，则通过重复应用“11 → 1”运算将所有 1 减少为单个“1”。 
4. 通过放置单个“1”后跟全零来构造输出。 这可确保不出现前导零，并且在二进制比较下该值最小化。 

关键的推理步骤是，一旦允许自由交换，位置结构就毫无意义，而一旦存在压缩，多个位置结构就会崩溃为单个代表。 唯一不可约的信息是该数字是零还是正数以及还剩下多少个零。 

### 为什么它有效

 不变量是多组字符减少为全零或恰好一个“1”加零。 交换保留计数，并且压缩规则严格减少计数的数量而不增加值。 因此，每个可达状态相当于最多有一个“1”的配置，并且在这些配置中，将单个“1”放在全零之前会产生最小的二进制值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()

if '1' not in s:
    print("0")
else:
    zeros = s.count('0')
    print("1" + "0" * zeros)
```该实现直接对算法中描述的减少进行编码。 检查是否存在“1”可以处理简并零的情况。 计算零就足够了，因为所有的零都会分解为一个代表。 最终的结构通过将唯一的“1”放置在最高有效位置来确保尽可能小的二进制值。 

一个常见的陷阱是试图在交换后保留相对顺序，但交换会使任何位置约束失效。 另一个微妙的问题是忘记了多个在最终的简化形式中不会保持多个。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = sys.stdin.readline().strip()
    if '1' not in s:
        return "0"
    return "1" + "0" * s.count('0')

# provided sample
assert run("4\n1001\n") == "100"

# all zeros (edge)
assert run("3\n000\n") == "0"

# single one
assert run("1\n1\n") == "1"

# all ones
assert run("5\n11111\n") == "1"

# mixed
assert run("5\n10101\n") == "1000"

 ## 边缘情况

 关键的边缘情况是字符串仅包含零。 在这种情况下，任何交换或压缩都无法改变任何内容，并且正确的输出仍然是“0”。 该算法通过检查是否缺少“1”来显式处理此问题。 

另一个边缘情况是完全由 1 组成的字符串。 重复应用压缩规则将任意长度的连续值减少为单个“1”，并且交换是无关的。 实现自然会产生“1”。 

诸如“10101”之类的混合排列可能表明需要位置优化，但由于交换允许任意排列，因此最终状态会忽略原始排序。 该算法正确地将其减少为单个 1 后跟零，从而确认结构完全由计数而不是排列决定。
