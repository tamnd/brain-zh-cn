 ## 解决方案
 ## 问题理解

 我们得到一串小写英文字母，并且允许我们使用固定次数的操作来修改它。 每个操作都会选取一个字符，并将其在循环字母表中向前或向后移动一步，其中`a`如下`z`和`z`如下`a`。 

任务是准确地花费`k`此类操作并最终得到按字典顺序排列的最小可能结果字符串。 每个操作仅影响一个角色，并且成本是统一的：向任一方向移动一个位置总是花费一次移动。 

输出是精确分配后的最佳最终字符串`k`以我们喜欢的任何方式在角色之间移动。 

形成解决方案的主要约束是所有测试用例的总长度最多为`4 · 10^5`， 尽管`k`可以大到`10^9`。 这立即排除了对所有可能的转换的任何模拟或对整个字符串的每个操作的贪婪重新评估。 任何花费时间与`k`是不可能的。 我们也不能在不协调剩余预算的情况下独立对待每个角色，因为在一个角色上花费额外的动作可能会迫使以后做出更糟糕的选择。 

出现微妙的边缘情况时`k`与总的“有用”改进相比，这是很大的。 例如，如果一个字符串已经是全部`'a'`，每次移动只会增加距离，而不会改善字典顺序，因此我们仍然必须消耗所有移动，可能是通过振荡字符来消耗。 一个试图“只改进字母”的天真贪婪者将无法解释剩余预算并产生错误的答案。 

另一个棘手的情况来自奇偶校验。 因为我们必须准确地使用`k`步，有时即使达到字典顺序的最佳配置，我们也被迫浪费一步。 这种浪费只能通过向前然后向后移动字符来实现，反之亦然，这会保留字符串，但会消耗两次移动。 这很重要，当`k`剩下的是奇数。 

## 方法

 暴力的观点是独立地考虑每个角色，并尝试它的所有可能的最终字母，以及跨位置的所有操作分布。 对于单个字符，将其转换为`s[i]`写给某封信`c`花费字母表上的最小圆形距离。 如果我们忽略全局约束`k`，我们可以贪婪地将每个字符变成`'a'`如果可能的话。 问题是我们必须准确地使用`k`最多不会动`k`，并且动作只能通过剩余预算才能在角色之间进行交互。 

完整的蛮力会尝试所有可能的分配`k`跨业务运营`n`位置和所有可能的目标字母。 即使我们限制对成本的关注，分配操作的方法的数量也是组合的，大约为`O(k^n)`在最坏的解释中，这是完全不可行的。 

关键的结构观察是词典顺序主要取决于较早的字符。 这表明从左到右的贪婪策略：我们希望早期的角色变得尽可能小，理想情况下`'a'`，因为那里的任何改进都会主导字符串后面的更改。 

对于每个角色，我们计算将其变成的最小成本`'a'`。 如果我们有足够的预算，我们就会应用它。 否则，我们将使用剩余的预算来尽可能接近`'a'`尽可能。 循环性质确保了剩余的移动可以在不改变最优性的情况下被吸收：一旦我们决定了剩余预算下可实现的最佳字母，剩余的平价就可以通过最终调整来处理。 

这将问题减少到具有运行预算的每个角色决策，而不是全局组合。

 ## 算法演练

 1. 对于每个角色`s[i]`，计算圆距离`'a'`。 这给出了制作该角色所需的最少移动次数`'a'`。 

这计算为`min((c - 'a') % 26, ('a' - c) % 26)`。 
2.如果剩余预算`k`至少是这个距离，减少`k`相应地将字符设置为`'a'`。 

这是最佳的，因为使前面的字符尽可能小总是可以改善字典顺序。 
3.如果`k`小于所需距离，我们无法到达`'a'`。 相反，我们将角色移动得尽可能远`'a'`尽可能使用`k`在周期中朝着更便宜的方向迈进。 

这会产生一个新角色`c' = (c - k) mod 26`或者`(c + k) mod 26`，以更接近的为准`'a'`。 
4. 一旦我们消耗完所有有用的减少量，任何剩余的`k`不需要改变词典结构。 由于移动是成对可逆的，因此剩余预算与最终字符串无关，因此实际上可以忽略不计。 

最终的配置已经尽可能地最小化每个前缀。 

### 为什么它有效

 核心不变量是在每个位置`i`，在处理之前，我们已经最大化了所有位置的字典序效益`< i`考虑到剩余预算。 由于字典顺序是从左到右决定的，因此后面的操作无法补偿较早的次优字符。 

循环成本结构确保了独立性：改变一个角色不会影响其他角色的成本结构。 因此，贪婪的选择让每个角色都尽可能接近`'a'`在剩余预算下尽可能实现局部最优且全球一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def dist_to_a(c):
    x = ord(c) - ord('a')
    return min(x, 26 - x)

def move_towards_a(c, k):
    x = ord(c) - ord('a')
    if x >= k:
        return chr(ord('a') + x - k)
    else:
        k -= x
        return chr(ord('a') + (26 - k) % 26)

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        s = list(input().strip())

        for i in range(n):
            d = dist_to_a(s[i])
            if k >= d:
                k -= d
                s[i] = 'a'
            else:
                s[i] = move_towards_a(s[i], k)
                k = 0

        out.append("".join(s))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```实施独立处理每个测试用例并维持运行预算`k`。 帮手`dist_to_a`计算最小循环距离`'a'`，它决定了我们是完全转换字符还是仅部分调整它。 

功能`move_towards_a`处理预算不足的情况。 它将角色移向`'a'`朝着更便宜的方向，如果需要的话可以环绕字母表。 这避免了明确地模拟逐步移动。 

循环严格从左到右，因为较早的字符主导字典顺序。 预算不断更新，确保我们永远不会后悔在早期位置上的支出。 

一个微妙的实现点是，一旦`k`耗尽后，后面的字符保持不变。 不需要传播任何额外的逻辑，因为进一步的修改无法在不重新访问早期位置的情况下改善字典顺序。

 ## 边缘情况

 关键的边缘情况是当字符串已经包含以下内容时`'a'`字符和`k`是非零的。 在这种情况下，仍然必须使用每一步，但字典顺序最小的字符串不会改变。 该算法处理这个问题是因为`dist_to_a`为零`'a'`，因此不消耗任何预算并且角色保持不变。 其余`k`变得无关紧要，因为不可能进一步改进。 

另一种情况是当`k`非常大。 由于每个字符都是独立处理的，因此该算法绝不会尝试应用超出必要范围的字符`'a'`。 一旦所有角色都最小化，多余的预算自然会被忽略。 

环绕式字母大小写，例如变换`'z'`，处理正确，因为循环距离计算总是选择较短的方向。 这确保了我们在迈向目标时绝不会超支或错过更便宜的路径`'a'`。
