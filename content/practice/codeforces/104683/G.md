 ## 解决方案
 ## 问题理解

 我们给定一个二进制字符串和一个固定的窗口长度$m$。 仅当每个连续子串的长度都满足时，该字符串才被视为有效$m$恰好包含$k$那些。 换句话说，如果我们滑动一个大小的窗口$m$在整个字符串中，每个窗口必须具有相同的人口数量，并且该人口数量固定为$k$。 

我们可以多次应用某个操作。 每个操作选择一个段$[l, r]$并翻转其中的所有位，将零变为一，将一变为零。 目标是将初始字符串转换为有效字符串，同时最大限度地减少此类段翻转的次数。 

约束条件$n \le 3000$总和为$n$也受$3000$跨测试用例意味着$O(n^2)$或者甚至每个测试用例解决方案稍差一点都是可以接受的，但必须避免最坏情况下的任何三次方。 这强烈暗示了位置或前缀状态上的动态编程或贪婪结构。 

这个问题的一个微妙之处是，有效性是在所有重叠窗口上定义的，这与位置紧密耦合。 独立修复每个窗口的简单方法将会失败，因为翻转一段会同时影响许多重叠的窗口。 

第二个常见的陷阱是假设我们可以贪婪地修复每个位置以匹配某些目标模式。 这是因为没有给出明确的目标字符串； 有效性是一个全局约束，而不是逐点等式约束。 

## 方法

 一个蛮力的想法是考虑所有可能的最终有效字符串，并计算将初始字符串转换为每个候选字符串所需的最小段翻转次数。 通过选择满足滑动窗口约束的任何一致分配来完全确定有效字符串。 然而，枚举这样的字符串是不可能的，因为约束是重叠的，并且一致配置的数量呈指数增长$n$。 

即使我们修复了候选目标字符串，计算将一个二进制字符串转换为另一个二进制字符串的最小段翻转次数本身也很重要。 它成为一个依赖于差异奇偶性的经典区间翻转问题，但对于指数级多个目标执行此操作会使该方法不可行。 

关键的结构观察是约束“每个长度窗口$m$正好有$k$“ones”强制执行强周期性依赖性。如果我们比较从位置开始的两个相邻窗口$i$和$i+1$，它们的总和仅通过去除$s[i]$并添加$s[i+m]$。 由于两者必须相等$k$，我们得到平等$s[i] = s[i+m]$。 这是关键的简化：整个字符串被强制分成独立的链，步骤$m$。 

因此，我们不再从窗口角度思考问题，而是将问题转化为$m$独立序列：索引同余模的位置$m$必须一致。 每个这样的链都有固定的长度$n/m$，并且在每个链中，所有值必须相同或遵循翻转后初始字符串引起的强制模式。 

一旦分解，问题就简化为决定每个残基类在最终配置中是否应该全零或全一，同时尊重每个窗口的总计数约束，这转化为准确选择$k$跨每个窗口的，由于周期性，它在所有窗口中变得一致。 

然后翻转操作就成为一种经典的成本结构：我们想要转换每个链的片段，最佳策略是计算最小翻转以使每个链一致，然后在全局约束下组合跨链的选择。 这导致 DP 超过剩余类别，其中每个类别设置为 0 或 1 时都会产生成本。

 ## 算法演练

 我们通过利用重叠约束隐含的周期结构来构建解决方案。 

1. 对于每个位置$i$，我们观察到它属于残基类$i \bmod m$。 同一类别中的所有位置在任何有效配置中都必须表现一致。 这直接来自于比较相邻窗口，这迫使位置距离相等$m$分开。 
2. 对于每个残留类别$c$，我们提取位置序列$c, c+m, c+2m, \dots$。 它们形成独立的链，因为没有窗口以破坏可分离性的方式混合来自不同链的元素。 
3. 对于每个链，我们计算使该链中的所有元素等于 0 的成本以及使它们全部等于 1 的成本。该成本只是与初始字符串不匹配的数量，因为链中的翻转段始终可以最佳地安排，以便以最少的操作匹配统一的目标。 
4. 我们现在重新解释窗口约束。 因为每个长度-$m$窗口必须恰好有$k$，并且每个窗口恰好包含每个残基类中的一个元素，因此最终分配必须准确选择$k$残基类别被赋值为1，其余的$m-k$类为 0。 
5. 因此，我们对$m$残留类。 让$dp[j]$是准确选择的最小成本$j$类作为迄今为止处理的类中的类。 对于每个类，我们通过将其分配为 0 或 1 来进行转换，并添加相应的成本。 
6.答案是$dp[k]$，因为我们必须准确选择$k$类成为一个。 

微妙之处在于，分解为残差类将全局重叠约束转变为局部组合选择问题。 如果没有这一步，DP 仍然会处于高度纠缠的状态空间上。 

### 为什么它有效

 正确性取决于具有相同索引模的所有位置的不变量$m$任何有效的最终字符串中都必须相同。 这将每个窗口约束减少为关于分配多少个残差类的约束 1。由于每个窗口恰好包含每个类的一个代表，因此每个窗口的数量等于选择为 1 的类的数量。因此，全局约束成为独立项上的固定基数约束，这正是 DP 强制执行的。 成本结构是跨类别的累加，因此最优子结构成立。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        s = input().strip()

        cost0 = []
        cost1 = []

        # compute cost per residue class
        for r in range(m):
            c0 = 0
            c1 = 0
            for i in range(r, n, m):
                if s[i] == '1':
                    c0 += 1
                else:
                    c1 += 1
            cost0.append(c0)
            cost1.append(c1)

        INF = 10**18
        dp = [INF] * (m + 1)
        dp[0] = 0

        for i in range(m):
            ndp = [INF] * (m + 1)
            for j in range(i + 1):
                if dp[j] == INF:
                    continue
                ndp[j] = min(ndp[j], dp[j] + cost0[i])
                ndp[j + 1] = min(ndp[j + 1], dp[j] + cost1[i])
            dp = ndp

        print(dp[k])

if __name__ == "__main__":
    solve()
```解决方案首先将索引分组为$m$残留类。 对于每个类，它计算两个成本：强制整个类为零或强制为一，通过与原始字符串的不匹配计数来衡量。 

然后 DP 准确选择$k$分配值 1 的类。每个转换对应于决定类的最终状态。 二维 DP 保持较小，因为类的数量仅为$m$，我们只跟踪计数$k$。 

一个微妙的实现细节是 DP 更新的方向：我们为每个类构建一个新的数组，以避免覆盖仍然需要的状态。 这可以防止在同一迭代中意外重用部分更新的状态。

 ## 边缘情况

 一个关键的边缘情况是当$m = n$。 在这种情况下，只有一个窗口，因此约束减少到整个字符串恰好具有$k$那些。 残渣分解产生$m$单例类，DP 只需选择$k$位置设置为 1。该算法自然会退化为选择最便宜的位进行翻转，这与预期的组合解释相匹配。 

另一个边缘情况是$m = 1$。 每个窗口都是一个字符，因此每个字符必须相等$k$，这会强制全零或全一，具体取决于$k$。 残基结构分解为一类，DP 立即正确地分配它而不会产生歧义。 

最后，当$k = 0$或者$k = m$，DP 只有一种有效的选择大小。 该算法仍然有效，因为它强制执行精确的基数，并且所有残基类别都被统一分配，从而产生单个全局翻转策略，最大限度地减少整个字符串的不匹配成本。
