 ## 解决方案
 ## 问题理解

 我们得到一棵有根树，其中每个节点除了根之外都有一个父节点。 两个令牌从根开始：蓝色令牌和红色令牌。 该过程以同步轮次展开。 在每一轮中，蓝色标记将一条边向下移动到第一个玩家选择的子项，然后红色标记也将一条边向下移动到第二个玩家选择的子项。 在两次移动之后，如果红色标记碰巧落在一片叶子上，则该叶子被视为“已收集”：我们递增答案，红色标记将被删除并立即替换在蓝色标记的当前位置。 游戏继续进行，直到蓝色标记在移动后到达叶子，此时该过程立即停止并且不会发生进一步的红色移动。 

目标是在蓝色令牌结束游戏之前最大化红色令牌在叶子上完成的次数。 

该树最多可以有二十万个节点，因此任何尝试模拟每对可能的移动或随着时间的推移显式维护两个标记的状态的解决方案都是不可行的。 每个状态二次甚至 n log n 的方法都会失败，因为两个玩家在每个深度都做出决策，并且幼稚的分支很快就会变成指数级的。 

一个微妙的边缘情况是当树是单链时。 在这种情况下，只有一片叶子，因此只能完成一个红色芯片。 另一个边缘情况是星形树，其中根有许多子叶。 在这种情况下，在蓝色下降之前，红色可以立即到达每片叶子，但蓝色仍然很快结束，答案只是叶子的数量。 任何假设更深层次结构和时序之间相互作用的解决方案都可能使这些情况变得过于复杂。 

## 方法

 乍一看，人们可能会尝试直接模拟该过程。 每个状态都取决于蓝色位置和红色位置，并且每一轮都分为两个玩家的选择。 这导致了一个巨大的游戏树：从每个节点对中，两个玩家都在子节点中进行选择，并且在此过程中红色可能会重置多次。 即使我们尝试记忆，状态空间实际上也是节点对，即 O(n²)，并且转换会进一步增加它。 这立即超出了 n 的限制，高达 2⋅10⁵。 

关键的观察结果是，蓝色令牌强加了严格的单调结构：它总是沿着单个根到叶路径向下移动，并且从不重新访问节点。 这意味着整个过程受到第一个玩家选择的单个下降链的限制。 第二个玩家的红色令牌不会影响该路径，除非在蓝色到达底部之前可以挤压多少叶子完成。 

现在重点关注什么才是真正成功的红色完成。 每次红色令牌到达一片叶子时，我们正好获得一个单位，然后红色令牌被传送到当前的蓝色位置。 重要的是，这种传送会消除之前红色进度的所有记忆。 因此，每次成功完成都是从蓝色当前占据的任何节点开始的一次独立“尝试”。 

这意味着红色标记反复尝试从蓝色标记所在的任何节点开始到达叶子，但每当完成时，任何未完成的进度都会被丢弃。 增加完成次数的唯一方法是确保在游戏结束之前，从尽可能多的蓝色位置中，至少存在一个红色可以到达的叶子。

因为两个玩家以相同的速度移动，所以蓝色令牌逐步到达树的更深部分，但这并不能阻止红色以有意义的方式从较早位置探索其他分支：过程的结构崩溃为关于可达性而不是时​​间的事实。 在终止之前的某个阶段，红色令牌最终可以到达每片叶子，无论交错如何，只要它位于树中即可。 

这将整个游戏简化为一个结构性问题：树中有多少片叶子。 每片叶子对应一个潜在的完整红片，并且任何叶子都不能被计数超过一次，因为在达到之后它会被吸收到最终答案中，并且没有机制可以“重新打开”它。 

因此，最优策略精确地实现了每片叶子的一次计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| --- | --- | ---|
 | 全游戏状态模拟 | O(n²) 或指数 | O(n²) | 太慢了 |
 | 数叶子| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取父数组并构建树表示。 每个节点的子节点都是根据给定的父链接确定的。 
2. 遍历所有节点并计算哪些节点是叶子。 当一个节点在构造的邻接表中没有子节点时，它就是一个叶子节点。 
3. 统计所有这样的叶节点。 
4. 输出计数作为答案。 

唯一重要的步骤是认识到游戏的结构不需要跟踪任一令牌随时间的移动。 红色令牌的重置确保每次成功完成都是独立的，蓝色令牌的路径仅决定终止，而不决定可实现的完成总数。 

### 为什么它有效

 关键的属性是，每次红色令牌到达叶子时，它都会为最终答案准确贡献 1 并立即重置，使每个贡献独立于之前的贡献。 由于该过程永远不会将两个叶子合并为一个完成，并且不允许对一个叶子进行两次计数，因此可实现的完成总数受到叶子数量的限制。 两个参与者的策略只能影响叶子到达的顺序，而不能影响叶子是否存在或者在终止之前至少可以被计数一次。 这使得叶子集对于确定答案来说既必要又充分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    p = list(map(int, input().split()))
    
    children = [[] for _ in range(n + 1)]
    
    for i, par in enumerate(p, start=2):
        children[par].append(i)
    
    leaves = 0
    for v in range(1, n + 1):
        if not children[v]:
            leaves += 1
    
    print(leaves)

if __name__ == "__main__":
    main()
```该实现使用从父数组派生的邻接列表来构造树。 然后它扫描所有节点并计算具有零个子节点的节点。 该解决方案避免了对游戏的任何模拟，因为游戏动态崩溃为纯粹的结构不变量：每个叶子恰好对应于一个可实现的红色完成。 

实现中的一个常见错误是忘记节点 1 在退化情况下也可以是叶子，例如 n = 1，但由于约束保证 n ≥ 2，因此这种情况不会发生。 另一个微妙之处是确保所有节点的子列表都正确初始化； 否则，没有显式子节点的节点可能会被错误分类。

 ## 边缘情况

 在一个纯粹的链条中`1 → 2 → 3 → 4`，算法仅将节点 4 标记为叶子。 逐步运行该过程，每个内部节点都只有一个子节点，因此除了最后一个之外，其他节点都不会被计算在内。 输出正确变为1。 

在根直接连接到所有其他节点的星形树中，每个子节点都没有后代。 邻接构造将除根之外的所有节点生成为叶，并且扫描将它们全部计数。 输出与根的直接子节点的数量相匹配，这与每个端点对应于不同的可能的红色完成这一事实相一致。 

在任何混合树中，内部分支不会影响计数规则，因为叶子状态仅取决于局部结构。 遍历正确地隔离了每个终端节点，无论其深度或其在蓝色路径中的位置如何。
