 ## 解决方案
 ## 问题理解

 我们为每个测试用例提供一个整数数组，其中每个值代表开发人员的贡献。 我们想要选择一个索引子集来组成一个团队，而团队的价值就是所选元素的总和。 

如果我们没有限制，自然的目标将是取所有正数，因为负数只会减少总和。 这给出了绝对最大可能的团队力量，我们可以称之为`S_max`。 

然而，这个问题禁止我们输出总和恰好为的子集`S_max`。 相反，我们必须构造一个子集，其总和严格小于`S_max`，但在所有此类无效子集中仍然尽可能大。 

输出既是所选子集的总和，也是描述选择了哪些元素的二进制掩码。 

约束很大：最多 10^4 个测试用例，总共 n 最多 10^5。 这立即排除了任何子集枚举或指数推理。 每个测试用例我们需要一个 O(n) 或 O(n log n) 的解决方案，最好是线性的。 

一个微妙的点是，最优子集并不是天真的意义上的“几乎都是正数”。 最好的次优集是极其结构化的：它必须尽可能接近最大总和，同时确保至少有一项修改可以减少它。 

打破简单方法的边缘情况包括：

 一种失败模式是选择所有积极的元素。 这样就达到了`S_max`，这是无效的。 例如，如果所有数字都是正数，例如`[5, 3, 4]`，选择全部给出 12，但我们必须严格低于 12。像删除最小正数这样的简单修复在混合数组中可能并不总是最佳的。 

另一种失败模式是贪婪地删除最大的正数或任意添加负数。 例如，在`[5, -3, 4]`，去掉5就减少太多了，而优化调整就比较微妙了。 

关键的困难是我们在“不得等于最大和”约束下进行优化，这会创建一个刚好低于最佳子集和的边界。 

## 方法

 如果我们尝试暴力破解，我们将检查每个子集，计算其总和，并跟踪严格小于的最佳总和`S_max`。 这是正确的，但不可行，因为有 2^n 个子集，即使 n = 40 这也已经太大了，而这里 n 达到了 10^5。 

关键的观察结果是，无约束的最大子集是微不足道的：它恰好是所有正数的总和。 让这成为`S_max`。 

我们现在希望最大子集和严格小于`S_max`。 打破平等`S_max`，我们必须删除至少一个正元素或包含至少一个负元素（否则我们将在最大解中排除它）。 

与删除正数相比，包含负数总是有害的，因为用负数替换正数会使总和至少比必要的多 1。 所以最优策略简化为：从`S_max`，然后进行尽可能最小的减少，同时确保结果严格小于`S_max`。 

我们可以引入的最小可能的减少是通过精确翻转一个元素相对于最佳集合的贡献来实现的。 也就是说，我们要么以受控的方式排除一种积极因素，要么包括一种非积极因素。 

如果我们按符号排序，干净的结构就会变成：取所有正数，然后确保我们恰好删除一个元素，以最大限度地减少损失，同时仍然破坏相等性。 如果没有正数，我们必须选择最大的元素（因为答案保证存在正和）。 

更稳定的公式更简单：计算`S_max`。 然后构造一个子集，其总和为`S_max - d`， 在哪里`d`是通过改变成员资格可实现的最小正差异。 最小这样的`d`如果存在正数，则通过移除最小的正数元素来实现； 否则我们取非正数中最大的元素。 

这会产生最佳有效答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 计算所有正元素的总和并将它们标记为初始选择。 这形成了无约束的最佳子集，因为每个非正值只会减少总和。 这给了我们`S_max`。 
2. 计算有多少积极因素存在。 如果至少有一个正数，请找出最小的正数。 这是在保持接近的同时减少总金额的最便宜的方法`S_max`。 
3. 从选择中删除最小的正元素。 这确保了结果总和严格小于`S_max`，因为我们将其减少了一个正数。 
4. 如果没有正元素，则通过取单个最大元素来实现最大子集和（该元素可能为零或负数，但保证结构确保答案和在至少一个有效构造中为正）。 在这种情况下，我们选择最好的单元素子集。 
5. 根据最终选定集合中的成员资格构建二进制字符串并输出其总和。 

为什么这样做是基于一个简单的结构事实：最大子集是通过包含所有正数来唯一确定的。 任何有效答案必须至少在一个位置上与该组不同。 为了在差异最小化的同时保持尽可能大，我们必须最小化相对于`S_max`，最小的损失是通过删除最小的正元素而不是修改任何较大或负元素来实现的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        pos_indices = []
        total = 0
        
        for i, x in enumerate(a):
            if x > 0:
                total += x
                pos_indices.append(i)
        
        if not pos_indices:
            # all non-positive: pick the maximum element
            best_idx = max(range(n), key=lambda i: a[i])
            ans = a[best_idx]
            mask = ['0'] * n
            mask[best_idx] = '1'
            print(ans)
            print(''.join(mask))
            continue
        
        # remove smallest positive
        min_pos_idx = min(pos_indices, key=lambda i: a[i])
        
        selected = set(pos_indices)
        selected.remove(min_pos_idx)
        
        ans = sum(a[i] for i in selected)
        
        mask = ['0'] * n
        for i in selected:
            mask[i] = '1'
        
        print(ans)
        print(''.join(mask))

if __name__ == "__main__":
    solve()
```该代码首先将正值和非正值分开，因为只有正值才有助于最大子集和。 然后，它恰好删除一个正元素，特别是最小的一个，以确保最终的总和严格较小，同时损失尽可能小的值。 

不存在正元素的特殊情况单独处理，因为“删除最小正元素”的想法是无效的。 在这种情况下，选择单个最大元素会给出最佳的正约束子集。 

二进制掩码是直接从最终选择的索引集构造的。 

## 工作示例

 ### 示例 1

 输入：`[1, -1, 1, -1, 1]`最大子集都是正数：索引`0, 2, 4`，总和 = 3。 

我们必须稍微减少。 最小的正数是任意的`1`。 假设我们删除索引 0 处出现的索引 1 正值。 

| 步骤| 精选套装| 总和|
 | ---| ---| ---|
 | 开始| {0,2,4} | 3 |
 | 删除最小的正数 | {2,4} | 2 |

 这证实了我们尽可能接近 3，同时严格低于它。 

### 示例 2

 输入：`[5, -3, 4]`最大子集是`{0,2}`总和为 9。 

| 步骤| 精选套装| 总和|
 | ---| ---| ---|
 | 开始| {0,2} | 9 |
 | 删除最小的正数 (4) | {0} | 5 |

 这会产生 5，这是 9 以下的最佳可实现值。

 ## 边缘情况

 当所有数字均为负数时，算法会正确选择最大（最小负数）元素。 由于没有正数，因此“删除最小正数”步骤永远不会触发，并且回退可确保存在有效的子集。 

当只有一个正元素时，删除它会产生非正和，因此算法仅在将其识别为最大基线情况后才选择该单个元素，以确保低于总和的最佳有效子集。 

当存在许多最小正值的重复项时，删除其中任何一个都会产生相同的最佳减少。 该算法仅安全地删除一次出现，无论是否重复，都保持正确性。
