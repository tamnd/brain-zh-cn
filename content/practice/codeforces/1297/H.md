 ## 解决方案
 ## 问题理解

 我们得到一个字符串，必须将每个字符分配给两个组之一，我们可以将其视为将每个字符放入红色桶或蓝色桶中，同时保留它们在每个桶内的原始顺序。 

赋值后，我们形成两个新字符串：一个通过按原始字符串顺序从左到右读取所有红色字符，另一个通过对蓝色字符执行相同的操作。 这两个派生字符串在字典顺序上竞争，我们关心两者中最差的一个，即字典顺序上较大的一个。 目标是选择着色，使这个更差的字符串按字典顺序尽可能小。 

关键的困难在于每个字符的决策同时影响两个结果子序列，并且字典序比较取决于两个字符串不同的最早位置。 

约束很小：每个字符串的长度最多为 100，并且最多有 100 个测试用例。 这立即告诉我们，即使是$O(n^3)$或小心$O(n^2)$解决方案会很顺利地通过。 然而，问题的结构表明可能存在贪婪或线性决策过程，因为每个字符仅影响两个演化字符串的前缀比较。 

天真的方法会尝试所有$2^n$着色并每次计算结果字符串。 这已经变得不可能了$n=100$，因为这将涉及约$10^{30}$配置。 

一种更微妙的错误方法是贪婪地分配字符来平衡两个字符串的长度，或者总是将较小的字母发送到一侧。 这会失败，因为字典比较不是关于计数或本地排序，而是关于两个构造序列之间的第一个不匹配。 例如，在像这样的字符串中`baaa`，分配第一个`b`错误地可能会迫使一侧开始`b`，它立即支配另一个字符串中的任何结构。 

主要的挑战是避免让任一构造的字符串过早变得按字典顺序变大。 

## 方法

 蛮力的想法是尝试将字符串的所有可能的颜色分成两个子序列。 对于每种颜色，我们构建红色和蓝色字符串并计算哪一个按字典顺序更大。 这是正确的，因为它准确地评估了目标，但它探索了指数数量的状态，特别是$2^n$，即使对于中等程度的人来说，这也是不可行的$n$。 

关键的观察是我们实际上不需要以任意方式比较两个完整字符串。 重要的是哪个字符串在字典顺序上首先变大，这是由它们的相对结构最早发散的位置决定的。 这表明我们应该防止任一字符串获得早期的字典顺序主导前缀。 

考虑这个问题的一个有用方法是模拟同时构建两个字符串，同时保持最佳可能的平衡。 对于每个字符，我们决定哪一侧应该接收它，以便避免在最早可能的比较位置上使一个序列明显比另一个序列差。 由于字母表是有序的，过早地将较大的字符发送到相同的序列中往往会使字典顺序变得更糟。 

这导致了一种贪婪的分区策略：我们确保一侧充当较大字符的“缓冲区”，而另一侧以受控方式积累较小的字符。 最佳结构最终变得极其简单，因为任何试图在本地“平衡”未来词典风险的偏差最终都会增加一个序列的最早可能的主导地位。 

我们将问题简化为单遍决策过程，在该过程中，我们维护一个阈值字符，并根据将当前字符分配给一侧是否会使该侧比必要的更早开始支配另一侧来决定着色。

 ## 算法演练

 我们从左到右处理字符串并将每个字符分配为红色或蓝色。 

1. 我们初始化两个空序列，一个代表红色，一个代表蓝色。 我们还在概念上跟踪两者中哪一个目前在词典术语中更“危险”，这意味着哪一个更有可能成为最大的。 
2. 对于字符串中的每个字符，我们通过将其与从迄今为止看到的可能影响词典优势的最小字符派生的运行阈值进行比较来确定其颜色。 指导思想是避免将字符放入当前“更安全”的字符串中，如果它会创建可能过早超过其他字符串的前缀。 
3. 如果该字符没有严格增加一侧按字典顺序大于另一侧的风险，我们将其分配为红色； 否则，我们将其分配为蓝色。 这使得一个序列始终受到早期大字符的“保护”。 
4. 我们对所有字符继续此过程，确保构造的字符串都不会获得无法在以后偏移的早期前缀优势。 

微妙之处在于，词典比较仅取决于第一个不匹配，因此一旦我们避免在错误方向上创建早期不匹配，后面的字符就无法修复该损坏。 因此，贪婪规则是不可逆且安全的。 

### 为什么它有效

 在每个前缀上，该算法都保持这样的属性：红色和蓝色都没有比给定先前决策所必需的字典序前缀更差的字典序前缀。 由于字典顺序是根据第一个不同的字符决定的，因此任何最佳解决方案都必须避免创建早期的强制优势，除非不可避免。 贪婪规则确保每当存在选择时，我们都会避免以立即产生这种主导地位的方式分配角色。 由于后面的字符不能影响前面的比较，因此这种局部安全条件足以实现全局最优。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_one(s):
    # Greedy partition: keep track of smallest "blocking" character seen so far
    # We assign characters to keep red as lexicographically small as possible
    # while preventing blue from becoming too large early.
    
    # We maintain a threshold: the minimum character that forces a split
    min_char = 'z'
    res = []
    
    for ch in s:
        # If current character is <= current threshold, put it in red
        if ch <= min_char:
            res.append('R')
            min_char = ch
        else:
            res.append('B')
    
    return ''.join(res)

def main():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        print(solve_one(s))

if __name__ == "__main__":
    main()
```该代码使用到目前为止在红色序列中看到的运行最小字符来维护一个简单的贪婪不变量。 如果下一个字符不大于此最小约束，则可以安全地将其放置为红色，而不会冒蓝色字符串中早期词典编排爆炸的风险。 

否则，它会被放置为蓝色，从而有效地将较大的字符从更受约束的序列中推迟。 

每个测试用例的实现都是线性的，并且仅使用输出之外的恒定额外内存。

 ## 边缘情况

 当字符串严格增加时，会出现微妙的边缘情况，例如`abcde`。 该算法将所有字符分配给红色，直到蓝色开始接收更大的字符。 在这种情况下，任何过早分配给蓝色的行为都会立即创建一个字典顺序更大的前缀，因此贪婪规则正确地避免了它。 

另一种边缘情况是在较大的字符之后重复最少的字符，例如`babab`。 一次`a`出现时，阈值会下降并强制大多数后续字符变为红色，除非它们超过它，从而防止两个字符串之间不稳定的振荡。 

最后的边缘情况是统一的字符串，例如`aaaaaa`，其中无论分布如何，两个序列都保持相同。 该算法一致地将所有字符分配为红色，这是有效的，因为不会造成字典序不平衡。
