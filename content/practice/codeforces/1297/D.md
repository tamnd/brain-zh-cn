 ## 解决方案
 ## 问题理解

 每个员工都有固定的基本工资，我们可以额外分配整数奖金，这样所有员工的奖金总额正好是`k`。 加上奖金后，每个员工的最终工资就是他们原来的工资加上分配的奖金。 

影响分布的结构要求有三项。 首先，员工的薪资排名不得改变，因此，如果一名员工最初的薪资高于另一名员工，那么在扣除奖金后，他们的排名仍然必须严格高于另一名员工。 其次，所有最终工资必须保持不同。 第三，在所有有效的分配中，我们希望最终工资的最大值尽可能小。 

关键的紧张点是奖金可以自由分配，但它们必须保持顺序，避免冲突，并共同形成固定预算，同时保持最大最终值最小。 

这些约束提出了一个最坏的解决方案$O(n \log n)$每个测试用例。 高达$10^5$员工总数，$O(n^2)$或者任何涉及每个元素重复线性扫描的事情都会太慢。 允许排序，但在最坏情况的输入下，任何涉及嵌套调整或每个候选值重复可行性检查的操作都会失败。 

严格的顺序和独特性的结合产生了一个微妙的问题。 如果两名员工的调整值太接近，即使相差 1，我们也会打破“全部不同”条件。 另一种失败模式是贪婪分配，它尊重顺序但忽略总和的全局可行性`k`，很容易超出或低于所需的总数。 

## 方法

 一种直接的方法是考虑在保持约束的情况下任意分配奖金。 人们可能会尝试从最高工资向下分配奖金，始终确保下一个最终工资至少比前一个多一份。 这保留了顺序和唯一性，但它不控制总和。 如果我们然后尝试调整值以准确命中`k`，我们最终遇到了一个复杂的平衡问题，其中局部变化在全球范围内传播。 

另一种暴力观点是将最终工资视为严格递增的序列，它必须主导原始工资。 我们可以尝试猜测最终的最高工资`M`然后贪婪地分配其下最小的有效值。 对于固定的`M`，检查可行性是线性的。 但尝试一切`M`值会导致很大的搜索空间，而简单的二分搜索仍然需要仔细构建序列。 

关键的见解是扭转观点：我们不直接分配奖金，而是将最终工资视为受下限约束的严格递增序列`a_i`。 一旦我们对员工进行排序`a_i`，我们强制最终值必须严格递增，并且每个至少`a_i`。 这将问题转化为在总和约束下构造字典序最小可行递增序列，然后将其均匀向上平移以精确消耗`k`。 

建设工程分两期进行。 首先，我们构建满足排序和唯一性的最小有效最终数组。 其次，我们观察到，以受控方式增加所有最终值，同时保留差异，可以让我们从最后向后均匀分配剩余预算，而不会打破约束。 这就是结构变得线性和贪婪而不是组合的地方。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 强力调整 | O(n²) | O(n) | 太慢了|
 | 排序贪心构造 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们首先按基本工资对员工进行排序，同时跟踪原始指数。 

1. 对员工进行排序`a_i`按递增顺序。 这修复了所需的最终顺序，因为最终顺序必须与原始顺序匹配。 
2. 开始构建暂定的最终数组`b`， 在哪里`b[i]`表示第 i 个最小员工的最终工资。 初始化`b[0] = a[0]`。 
3. 对于下一个员工，设置`b[i] = max(a[i], b[i-1] + 1)`。 这同时保证了两件事：没有人违反原始顺序，并且所有最终值都保持严格递增。 

这样做的原因是排序约束一旦排序就减少为简单的单调要求，并且唯一性成为直接的“+1 间隙”约束。 

1. 计算所需的总基数`S = sum(b[i] - a[i])`。 这是在约束下可能的最小奖金分配。 
2.如果`S > k`，该实例是不可能的，但问题保证了可行性。 
3.让`rem = k - S`。 我们现在需要在不打破限制的情况下分配剩余的金额。 
4. 从最后一个员工开始向后迭代。 在每个位置，我们都可以安全地增加`b[i]`只要它仍然严格大于`b[i-1] + 1`没有违反。 实际上，我们可以增加`b[i]`只要它相对于邻居仍然有效，就不会影响排序。 

更简单的观点是，增加后面的元素只会将最大值向上推，不会影响前面的约束。 所以我们分发`rem`贪婪地从右到左。 

1.最后计算`d[i] = b[i] - a[i]`按原始顺序。 

### 为什么它有效

 排序结构强制执行满足排序和明确性的最小结构。 任何有效的解决方案都必须具有至少与此贪婪基线一样大的最终值，因为减少任何元素都会违反下限`a_i`或打破严格的顺序。 一旦这条基线被固定，剩下的自由度只在于在保持顺序的同时均匀增加元素，从右侧应用总是最安全的，因为它不会影响未来的约束。 这保证了我们准确地达到`k`不违反单调性或唯一性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    order = sorted(range(n), key=lambda i: a[i])
    pos = [0] * n
    
    b = [0] * n
    b[0] = a[order[0]]
    
    pos[order[0]] = 0
    
    for i in range(1, n):
        idx = order[i]
        prev_idx = order[i-1]
        pos[idx] = i
        b[i] = max(a[idx], b[i-1] + 1)
    
    # compute minimal required bonus
    base = sum(b[i] - a[order[i]] for i in range(n))
    rem = k - base
    
    # distribute remaining from right to left
    for i in range(n-1, -1, -1):
        if rem == 0:
            break
        if i == 0:
            add = rem
        else:
            # we can safely increase without breaking ordering
            add = rem
        
        b[i] += add
        rem -= add
    
    ans = [0] * n
    for i in range(n):
        ans[order[i]] = b[i] - a[order[i]]
    
    print(*ans)

t = int(input())
for _ in range(t):
    solve()
```该解决方案首先对员工进行分类，以便所有约束都减少到本地邻居关系。 的建设`b`强制执行高于原始工资的最小有效严格递增序列。 然后剩余的预算被推到最右边的位置，因为它们不限制未来的元素。 

关键的实现细节是维护到原始索引的映射。 如果没有这个，我们将失去构造序列和所需输出顺序之间的对应关系。 

## 工作示例

 ### 示例 1

 输入：```
n=4, k=1
a = [3, 1, 4, 2]
```排序顺序是`[1, 2, 3, 4]`按价值 → 指数`[1, 3, 0, 2]`。 

我们建造最小的`b`:

 | 步骤| 员工 | 一个 | 前一个 | 计算出的 b |
 | ---| ---| ---| ---| ---|
 | 0 | 1 | 1 | - | 1 |
 | 1 | 3 | 2 | 1 | 2 |
 | 2 | 0 | 3 | 2 | 3 |
 | 3 | 2 | 4 | 3 | 4 |

 所以最低奖金是`[0,0,0,0]`，总和为 0，rem = 1。 

我们将 1 添加到最后一个元素 → 最终元素`b = [1,2,3,5]`按排序顺序。 映射回给出有效的分布。 

这证实了最右边的元素吸收了剩余的元素而不破坏顺序。 

### 示例 2

 输入：```
n=2, k=3
a = [10, 2]
```排序：`[2, 10]`。 

构建最小化`b`:

 | 步骤| 一个 | 上一个 | 乙|
 | ---| ---| ---| ---|
 | 0 | 2 | - | 2 |
 | 1 | 10 | 10 2 | 10 | 10

 基本奖金为 0，rem = 3。 

我们向最后一个元素添加 3：`b = [2, 13]`。 

奖金变成`[3, 3]`映射回原始索引。 

这显示了即使在大量剩余重新分配的情况下，该结构也如何保持顺序。

def run(inp: str) -> str:

        return " ".join(map(str, ans))

    t = int(input())

        out.append(solve())

 ## 边缘情况

 一种边缘情况是当`n = 1`。 该算法立即将全部奖金分配给该员工，并且由于不存在排序约束，因此该结构仍然成立。 

另一种情况是工资顺序相反。 排序的结构确保我们始终按升序处理它们，因此即使极端的输入排列也会简化为干净的单调序列。 最后的映射步骤正确地恢复了原始位置。 

最后一个微妙的情况是`k = 0`。 基线构建已经满足最低条件，因此不会发生重新分配。 所有员工的产出都是零奖金，并且所有约束仍然得到满足。
