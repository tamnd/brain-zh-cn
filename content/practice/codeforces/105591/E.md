 ## 解决方案
 ## 问题理解

 我们得到一个由小写拉丁字母组成的字符串。 如果字符串包含至少出现相同字符的任何连续块，则该字符串被视为“无聊”`m`连续多次。 我们的任务是使用两个允许的操作将字符串转换为非无聊字符串：以成本 1 删除一个字符，或以成本 1 的任何位置插入任意字符`k`。 插入可以放置在任意两个现有字符之间或末尾。 

目标是最小化总成本，以便在所有编辑之后，不会出现任何字符`m`或更多。 

约束允许字符串长度最大为 200,000，因此任何平方的解`n`将会失败。 我们期望在本质上线性时间或接近线性时间中处理字符串，这强烈表明我们应该将问题减少到独立的局部结构，而不是模拟全局编辑。 

一个关键的结构观察是只有相同字符的运行才重要。 任何对条件的违反都来自同一字母的最大连续段，因此字符串自然地分解为独立的块，并且应用于一个块的操作不会影响其他块。 

一个微妙但重要的一点是，删除不会将一个运行分解为同一字符的多个运行。 如果我们删除一个连续中的字符，该连续的剩余字符仍然相邻，并且仍然形成该字母的单个连续块。 这意味着只有插入不同的字符才能将运行分成多个安全部分。 

一个天真的错误是假设删除可以将长运行“分离”成更小的运行。 例如，在`"aaaaaa"`，删除中间字符不会创建多个运行`'a'`，它仍然成为较短的单次运行。 

边缘情况出现时`m`很小。 如果`m = 2`，禁止任何相邻的相同字符。 对于像这样的跑步`"aaaa"`，即使是一对也已经违反了条件。 另一个极端情况是当`k`非常大，使得插入基本上无用，或者当`k = 1`，使得插入与删除相比极其便宜。 

## 方法

 该字符串分解为相同字符的最大串。 考虑这样的一个长度`L`。 如果`L < m`，它已经满足条件并且不需要改变。 

如果`L ≥ m`，我们必须减少它，以便没有相同字符的片段达到长度`m`。 

暴力方法将模拟字符串中所有可能的删除和插入序列，探索不同的方式来分割运行并动态支付成本。 这很快就变得不可行，因为每次运行的长度`L`有指数级多种方式来交错插入和删除，并且`n`高达200,000，这远远超出了任何可行的状态空间。 

关键的见解是每次运行都可以独立处理，对于单次运行我们只需要比较两种根本不同的策略。 

第一个策略是删除字符，直到游程长度变为`m - 1`。 这完全避免了插入，而成本纯粹是删除的次数，即`L - (m - 1)`。 

第二种策略是保留所有字符并插入分隔符，以便相同字母的片段不会超过长度`m - 1`。 每次插入都会将长运行分割成更小的有效片段。 如果我们有一个运行长度`L`，我们需要在每个之后插入一个分隔符`m - 1`字符，这会导致`floor((L - 1) / (m - 1))`插入，每次成本计算`k`。 

最佳解决方案就是每次运行取这两个成本中的最小值，因为混合部分删除和插入不会将成本提高到超出这些极端值。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 最优（运行分解）| O(n) | O(1) 额外 | 已接受 |

 ## 算法演练

 对于字符串中相同字符的每个最大分段，我们计算使该分段有效的最小成本并将其添加到答案中。 

1. 从左到右扫描字符串，将连续的相等字符分组为一个带有长度的游程`L`。 此步骤隔离独立的结构，因为运行内的操作不会影响其他运行。 
2.如果`L < m`，对于这次运行不执行任何操作，因为它已经满足约束。 
3.如果`L ≥ m`，计算删除成本为`L - (m - 1)`。 这相当于减少运行，使其永远无法达到`m`连续的字符。 
4. 将插入成本计算为`((L - 1) // (m - 1)) * k`。 这对应于插入分隔符，以便每个相同字母的块在达到长度之前被破坏`m`。 
5. 将这两个成本中的最小值添加到总答案中。 

该算法在字符串中线性进行，仅维护当前的游程长度，因此不需要存储或重新访问字符串的先前部分。 

### 为什么它有效

 每次运行都是独立的，因为对一种字符类型的操作不会影响不同字符类型的相邻性。 在运行内部，删除只会减少长度，但不会将运行拆分为多个安全组件，因此删除的唯一有意义的效果是减少总长度。 插入是在运行中创建分离的唯一机制。 因此，任何有效的最终运行配置都必须可以通过删除将其降低到阈值以下或使用插入将其拆分来实现，并且这两种机制充分表征了所有可行的结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    s = input().strip()

    ans = 0
    i = 0

    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1

        L = j - i

        if L >= m:
            delete_cost = L - (m - 1)
            insert_cost = ((L - 1) // (m - 1)) * k
            ans += min(delete_cost, insert_cost)

        i = j

    print(ans)

if __name__ == "__main__":
    solve()
```该实现是基于运行的推理的直接翻译。 内部循环提取每个最大的相等字符块。 对于每个块，我们计算其长度并评估两个候选成本。 

一个常见的实施陷阱是对插入的楼层划分处理不当。 正确的公式取决于将字符分组为大小的块`m - 1`，分隔符的数量恰好是这些块之间的完整边界的数量，即`(L - 1) // (m - 1)`。 

另一个微妙的点是确保我们只在以下情况下应用成本：`L ≥ m`。 对于较短的运行，这两个公式都会错误地生成正值或无意义的值，因此必须显式跳过它们。

 ## 边缘情况

 对于由单个长串组成的字符串，例如`"aaaaaaa"`和`m = 2`，该算法将其作为一个块进行处理，并将删除单个字符与在每个字符之间插入分隔符进行比较。 删除路径成本`L - 1`，而插入成本`(L - 1) * k`。 和`k ≥ 1`，删除总是最优的，除非`k = 1`，其中两者变得相等，并且算法仍然正确选择。 

对于交替字符串，例如`"abababab"`，每次运行的长度为1，因此不会产生任何成本，算法自然会跳过所有计算。 

对于以下情况`k`非常大，永远不会选择插入，因为它主导删除，并且该算法仅通过删除正确地减少每个长运行。
