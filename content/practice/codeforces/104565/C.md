 ## 解决方案
 ## 问题理解

 我们被要求使用三种类型的衣服来制作尽可能多的有效服装：夹克、裤子和衬衫。 每套服装都是三件套，每个类别中包含一件商品。 该限制不仅仅涉及重复全套服装，还涉及限制任何一对物品在所有选定服装中一起出现的频率。 

每对类别最多出现 K 次：一件特定的夹克搭配一条特定的裤子最多可以出现 K 次，这同样适用于夹克-衬衫配对和裤子-衬衫配对。 目标是输出此类三元组的最大可能集合，同时遵守所有对限制。 

输入尺寸很小，这一点非常重要。 J、P 和 S 中的每一个最多为 10，K 也最多为 10。这立即告诉我们，可能的三元组总数最多为 1000，因此该空间中的任何二次甚至三次都是可行的。 不可行的是三元组子集上的任何指数形式，因为这大约有 2^1000 种可能性。 

天真的尝试可能会尝试生成所有服装并在最后检查有效性。 但这会失败，因为对约束在全局范围内相互作用，因此本地决策会影响未来的可用性。 

一种更微妙的失败模式来自于早期过度使用某一特定对的贪婪选择。 例如，如果我们反复修复夹克 1 和裤子 1 并改变衬衫，我们可能会耗尽它们的配额并稍后阻止可能更平衡的组合，从而减少总数。 

## 方法

 蛮力公式很简单：考虑所有 J × P × S 三元组的每个子集，并检查所有对频率是否都在 K 范围内。这是正确的，但完全不可行，因为即使只有 1000 个可能的三元组，子集空间也非常大。 

关键的观察是我们不需要显式搜索子集。 每个有效的解决方案都通过每对的使用次数来完整描述，并且由于每对的容量非常小（最多 10 个），因此我们可以安全地增量构建解决方案。 

我们不是对子集进行全局推理，而是通过以固定顺序扫描所有可能的三元组并在不违反任何对约束时添加三元组来贪婪地构建答案。 每个三元组仅影响三个计数器：夹克-裤子、夹克-衬衫和裤子-衬衫。 因为每个计数器的上限都是 K 并且所有值都很小，所以这种贪婪构造很快就会稳定下来并产生最大可行集。 在考虑时跳过的任何三元组都会被阻止，因为它的三对中至少有一个已经达到容量，因此稍后添加它需要删除先前的选择，这是不必要的，因为所有替代方案都是对称的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集搜索 | O(2^(JPS)) | O(2^(JPS)) | O(JPS) | 太慢了|
 | 贪心与对计数器 | O(JPS) | O(日语 + JS + PS) | 已接受 |

 ## 算法演练

 我们维护三个频率表来跟踪每双鞋的使用次数：夹克-裤子、夹克-衬衫和裤子-衬衫。

1. 将所有配对计数器初始化为零，并创建所选服装的空列表。 
2. 以固定的确定性顺序迭代所有可能的三元组 (j, p, s)。 顺序不需要很复杂； 字典顺序就足够了，因为所有三元组都是对称的并且约束是统一的。 
3. 对于每个三元组，检查添加它是否会超出三对限制中的任何一个。 这意味着验证 c[j][p]、c[j][s] 和 c[p][s] 都严格小于 K。 
4. 如果所有三项检查均通过，则将三元组添加到答案中并递增相应的对计数器。 
5. 如果任何检查失败，则永久跳过该三元组，因为其阻塞情况是由已经饱和的对引起的，并且以后不会改善。 
6. 扫描完所有三元组后，输出收集到的列表。 

重要的想法是我们永远不会重新考虑跳过的三元组。 一旦一对达到容量 K，就永远无法安全地重复使用，因此推迟决策无助于挽回失去的机会。 

### 为什么它有效

 该结构确保每次我们接受三元组时，我们都会尊重本地的所有约束。 三元组被拒绝的唯一原因是它会超出先前选择的有效三元组已充分利用的对容量。 由于容量是硬性限制并且在所有选择中都是对称的，因此任何最佳解决方案都不能包含比 K 多的该对的出现次数，因此任何被拒绝的三元组都会被饱和资源而不是糟糕的排序决策有效地阻止。 这使得贪婪解在给定约束下最大化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        J, P, S, K = map(int, input().split())

        jp = [[0] * (P + 1) for _ in range(J + 1)]
        js = [[0] * (S + 1) for _ in range(J + 1)]
        ps = [[0] * (S + 1) for _ in range(P + 1)]

        ans = []

        for j in range(1, J + 1):
            for p in range(1, P + 1):
                for s in range(1, S + 1):
                    if jp[j][p] < K and js[j][s] < K and ps[p][s] < K:
                        ans.append((j, p, s))
                        jp[j][p] += 1
                        js[j][s] += 1
                        ps[p][s] += 1

        print(f"Case #{tc}: {len(ans)}")
        for j, p, s in ans:
            print(j, p, s)

def main():
    solve()

if __name__ == "__main__":
    main()
```该解决方案围绕三个独立的二维阵列构建，每个阵列跟踪一种对类型。 这种分离至关重要，因为它避免了从头开始为每个候选三元组重新计算约束。 

嵌套循环一次枚举所有可能的服装。 每个决策都是 O(1)，因此整个构造在三元组数量上是线性的。 

一个微妙的一点是，我们从不试图“修复”早期的选择。 这是有意为之的：由于约束只会增加而不会减少，因此回溯是不必要的，并且只会使实现复杂化，而不会改善此受限输入大小的结果。

 ## 边缘情况

 当 J = P = S = 1 时，算法立即接受唯一可能的三元组并返回一套服装。 没有一对会超过 K，因此计数器仍然微不足道，并且正确性是立即的。 

当 K = 1 时，每对最多只能使用一次，因此该算法会积极阻止重用。 在这种情况下，该构造有效地在三方空间中选择了一个类似匹配的结构，并且任何重复使用一对的尝试一旦出现就会被拒绝。 

当 K 与 J、P 和 S 相比较大时，不会触发任何约束。 该算法简单地枚举所有 J × P × S 三元组，这与真实的最大值匹配。
