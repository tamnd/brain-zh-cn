 ## 解决方案
 ## 问题理解

 该问题描述了一组`n`玩家中只有一名玩家是隐藏的冒名顶替者。 我们得到了对完成任务的玩家的观察。 出现在观察名单中的玩家不可能是冒名顶替者。 该列表可以多次包含同一玩家，因为看到某人执行多个任务并不会提供任何额外信息。 

目的是确定观察结果是否恰好留下了一个可能的冒名顶替者。 如果恰好有一个玩家从未见过执行某项任务，那么答案是`YES`。 如果有两个或更多可能的冒名顶替者，机组人员无法确定，答案是`NO`。 有一种特殊情况：如果每个玩家都出现在列表中，则信息不一致，因为冒名顶替者一定是伪造了一项任务，而问题不允许我们假设发生了这种情况。 答案也是`NO`。 

限制很小，玩家数量和观察数量最多`1000`。 这意味着即使使用简单线性扫描的解决方案也很容易足够快。 解决方案围绕`O(n + k)`仅执行几千次操作。 更复杂的方法（例如多次排序或重复检查所有玩家）是不必要的，尽管它们仍然可能会低于这些限制。 

主要的边缘情况来自于独特玩家的令人困惑的外观。 重复观察并不会减少可能的冒名顶替者的数量，因为被看到十次的玩家仍然只是一个被确认的非冒名顶替者。 

例如：```
3 3
1 2 2
```正确的输出是：```
YES
```玩家`1`和`2`已确认安全，因此只有玩家`3`可能是冒名顶替者。 粗心的实现会计算观察结果而不是不同的玩家，可能会认为找到了三个玩家并错误地回答`NO`。 

另一种情况是当每个玩家都出现时：```
3 5
2 1 1 3 3
```正确的输出是：```
NO
```人们看到这三名玩家都在执行任务。 由于冒名顶替者无法正常完成任务，因此我们没有可以确定的玩家身份。 

最后的边界情况是只有两个玩家时：```
2 2
2 2
```正确的输出是：```
YES
```唯一的玩家`2`被排除为冒名顶替者，留下玩家`1`作为独特的可能性。 

## 方法

 一种简单的暴力方法会尝试将每个玩家都视为可能的冒名顶替者。 对于每个候选人，我们可以检查该玩家是否出现在任务列表中。 如果玩家出现，他们就不可能了。 否则，我们将它们视为可能的答案。 这是正确的，因为我们拥有的唯一信息是玩家是否被观察过。 

这种方法的问题是重复扫描。 最多有`1000`球员和`1000`观察，所以最坏的情况执行大约`1,000,000`检查。 这仍然会在这里通过，但它正在解决一个比必要的更普遍的问题。 

关键的观察是我们并不关心玩家出现了多少次。 我们只需要知道哪些球员至少出现过一次。 一旦这些球员被标记，答案就取决于有多少球员未被标记。 

蛮力方法之所以有效，是因为它会问“这个玩家可能吗？” 对于每个玩家单独，但所有玩家都是独立的观察让我们可以立即回答所有候选人。 布尔数组记录是否看到每个玩家，从而将问题简化为计算未见过的玩家。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nk) | O(nk) | O(1) | O(1) | 此处接受，但不必要 |
 | 最佳 | O(n + k) | O(n) | 已接受 |

 ## 算法演练

 1. 创建一个数组，记录是否看到每个玩家正在执行任务。 最初，每个玩家都被认为是看不见的。 
2. 读取每个观察到的玩家并将该玩家标记为已观察。 重复出现不会改变任何事情，因为我们只关心玩家是否至少出现过一次。 
3. 数一下还没有看到的玩家。 这些球员正是可能成为冒名顶替者的候选人。 
4. 如果可能的冒名顶替者的数量恰好为 1，则打印`YES`。 否则打印`NO`。 

这样做的原因是，每个见过的玩家都被排除在外，而每个看不见的玩家仍然是可能的。 只有当剩下的一组恰好包含一名球员时，工作人员才能识别出冒名顶替者。 

为什么它有效：

 该算法保持了一个不变量，即在处理观察列表的任何前缀后，标记的玩家正是出现在该前缀中的玩家。 最后，每个不可能是冒名顶替者的玩家都会被标记。 剩下的唯一玩家是那些与所有观察结果一致的玩家。 如果有一个这样的玩家，那么冒名顶替者就被唯一确定。 如果有零个或多个候选人，那么确定性是不可能的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    seen = [False] * (n + 1)

    for _ in range(k):
        x = int(input().strip()) if False else None

    # Re-read input handling the second line containing all values
    data = list(map(int, input().split()))
    for x in data:
        seen[x] = True

    possible = 0
    for i in range(1, n + 1):
        if not seen[i]:
            possible += 1

    print("YES" if possible == 1 else "NO")

if __name__ == "__main__":
    solve()
```该实现使用按玩家编号索引的布尔数组。 由于玩家编号开始于`1`，数组有大小`n + 1`以便索引直接匹配玩家标识符。 

阅读观察结果后，列表中的每个玩家都会被标记。 重复值不需要特殊处理，因为分配`True`多次分配与分配一次效果相同。 

最后一个循环对未标记的玩家进行计数。 与的比较`1`是唯一需要的条件，因为零个候选者和多个候选者都意味着无法识别冒名顶替者。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + k) | 每个观察结果都会被处理一次，每个玩家都会被检查一次 |
 | 空间| O(n) | 布尔数组存储每个玩家是否被观察 |

 这些限制使得这种方法可以轻松实现。 至多有`1000`玩家，内存占用极小，运行时间远低于限制。

 ## 边缘情况

 当观察结果包含重复项时，算法只会将玩家的状态从不可见更改为可见一次。 

为了：```
3 3
1 2 2
```玩家`2`处理两次，但看到的状态在第一次出现后保持不变。 剩下的看不见的玩家是`3`，所以输出是`YES`。 

当每个玩家至少出现一次时：```
3 5
2 1 1 3 3
```最终看到的阵列标记了每个玩家。 可能的冒名顶替者的数量变为零。 由于没有可以识别为冒名顶替者的玩家，因此算法输出`NO`。 

当只有一名玩家看不见时：```
2 2
2 2
```算法标记玩家`2`并离开玩家`1`未标记。 可能的冒名顶替者数量恰好是 1，所以答案是`YES`。 这个案例证实了观察的数量并不重要，重要的是被淘汰的不同玩家的数量。
