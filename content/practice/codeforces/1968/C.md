 ## 解决方案
 ## 问题理解

 当仅知道连续元素之间的模差时，我们被要求重建一个整数数组。 更准确地说，我们得到的值描述了每个元素除以前一个元素时的行为，并且我们必须构造与所有这些余数相匹配的任何有效序列。 

构造的序列必须同时满足两个约束。 首先，每个元素必须位于一个大而固定的数值范围内，最多可达 10 亿。 其次，对于每个相邻的对，第二个元素除以第一个元素时必须产生给定的余数。 

关键的结构含义来自模的行为方式。 如果我们修复以前的值$a_{i-1}$，然后是下一个值$a_i$必须是算术形式$$a_i = k \cdot a_{i-1} + x_i$$对于一些非负整数$k$，还有$x_i < a_{i-1}$。 这种不等式不是可选的，它是任何有效构造的硬性要求。 

在一个非常重要的方面，约束很小：$n \le 500$每个测试用例和所有测试用例的总和是$2 \cdot 10^5$。 这立即表明我们应该以每个测试用例的线性构造为目标。 任何尝试搜索或回溯可能值的解决方案$a_i$会太慢，因为即使是适度的分支因子也会爆炸超过 500 个步骤。 

当出现微妙的边缘情况时$x_i = 0$。 在那种情况下，$a_i$必须是的倍数$a_{i-1}$。 忽略这一点并简单地分配任意值的天真尝试往往会在后续步骤中破坏整除性。 例如，如果一个人贪婪地选择较小的值，则很容易陷入困境，因为未来的约束会强制产生不可能的余数。 

另一个有问题的情况是当连续余数相对于较小的先前值而言较大时。 例如，如果$a_{i-1} = 3$但$x_i = 4$，该条件立即不可能。 这就告诉我们，施工时必须保证$a_{i-1}$总是足够大，而不是从之前小的随机选择中得出。 

## 方法

 蛮力策略会尝试选择每一个$a_i$通过尝试值高达$10^9$并检查它是否产生所需的余数$a_{i-1}$。 这在概念上是正确的，但不可行。 即使我们每一步只尝试有限数量的候选者，最坏的情况仍然会呈指数增长$n$，因为每个位置都取决于前一个位置，并且每个错误的选择都会向前传播。 

关键的观察是我们没有被要求最小化或优化任何东西。 我们只需要存在，这让我们可以自由地激进地夸大价值观以避免冲突。 一旦我们意识到这一点，问题就变成了构造问题而不是搜索问题。 

关键的结构思想是确保在每一步中，先前的值都严格大于当前的余数。 如果我们保证$$a_{i-1} > x_i$$那么我们总是可以选择$$a_i = a_{i-1} + x_i$$它自动满足模条件，因为：

 - 除以$a_{i-1}$叶商1
 - 余数正好是$x_i$因此，整个问题简化为确保序列严格递增并且始终主导下一个余数。 既然所有$x_i \le 500$，我们可以安全地从足够大的基值开​​始，然后继续添加。 

一个简单而可靠的选择是设置$a_1$作为一个大常数$10^9 - 500$，然后使用向前构建$a_i = a_{i-1} + x_i$。 这永远不会超出界限并保持有效性。

 ## 算法演练

 1.设置第一个元素$a_1$到一个很大的数字，例如$10^9 - 500$。 这保证了足够的空间，以便所有后来添加的内容都保持在范围内。 
2. 对于每个位置$i$从 2 到$n$， 定义$a_i = a_{i-1} + x_i$。 这确保了序列严格递增并保留对余数的控制。 
3. 输出构造好的数组。 

### 为什么它有效

 每一步$i$，我们有$a_i = a_{i-1} + x_i$。 自从$x_i < a_{i-1}$总是正确的，因为$a_{i-1}$开始时非常大并且只会增加，模运算的行为是可预测的：$$a_i \bmod a_{i-1} = (a_{i-1} + x_i) \bmod a_{i-1} = x_i$$这个恒等式直接来自模算术。 该结构永远不会违反界限，因为最大可能的增长是$500 \cdot 500 = 250000$，远低于$10^9$。 因此，每个约束都被确定性地满足。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        x = list(map(int, input().split()))
        
        a = [0] * n
        a[0] = 10**9 - 500
        
        for i in range(1, n):
            a[i] = a[i - 1] + x[i - 1]
        
        print(*a)

if __name__ == "__main__":
    solve()
```实施直接遵循建设性想法。 唯一的设计选择是大的初始偏移，这保证不会溢出或无效的模块化行为。 每个下一个值都是在恒定时间内导出的，保留了线性复杂性。

 ## 边缘情况

 ### 大余数等于 500

 输入：```
n = 2, x = [500]
```我们设定$a_1 = 999999500$， 所以$a_2 = 1000000000$。 自从$a_2 - a_1 = 500$，我们得到$a_2 \bmod a_1 = 500$。 由于我们有意留出 500 的余量，因此构造保持在范围内。 

### 所有的

 输入：```
n = 5, x = [1, 1, 1, 1]
```序列变为：```
999999500, 999999501, 999999502, 999999503, 999999504
```每一步都保留了不变量，因为加 1 可确保除以前一项时余数为 1。 

### 最大链长度

 当$n = 500$和所有$x_i = 500$，最终值最多增加$250000$，仍远低于$10^9$。 这确认了初始缓冲区是足够的并且在任何步骤中都没有发生溢出。
