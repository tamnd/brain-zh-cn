 ## 解决方案
 ## 问题理解

 我们得到了一组时间间隔，每个间隔属于不同的讲师。 讲师 i 从 li 到 ri 的连续几天都有空，并且最多可以被分配到一个会议日。 

我们的任务不是直接挑选讲师，而是选择一个连续的日子段，并检查我们是否可以在该时段的每天安排一位不同的讲师，以便每位选定的讲师在分配的当天都有空。 

对于每一个可能的长度k，我们必须计算可以选择多少个长度为k的日段，以便这种分配是可行的。 

重新构建问题的一个有用方法是固定一段日期 [L, R]。 如果我们可以将其中的每一天与覆盖该天的不同间隔相匹配，则该段是有效的。 这是仅限于该窗口的天数和间隔之间的二分匹配问题。 

约束很大，间隔最多 200,000 个，日坐标最多 200,000 个。 尝试所有段并为每个段运行匹配或贪婪分配的任何解决方案都将立即失败，因为存在 O(n^2) 个段，并且每次检查至少是 n 中的对数或线性。 

一些微妙的边缘情况突显了天真的推理失败的原因。 

如果所有间隔都相同，例如 [1, 1] 重复多次，则只有长度为 1 的片段有效，因为不同的讲师无法涵盖两个不同的日子。 仅检查覆盖范围的幼稚方法可能会错误地假设较长的段有效。 

如果间隔很长但起始位置稀疏，例如 [1, 100000]、[2, 100000]，...，不强制执行唯一性的贪婪“覆盖率计数”可能会高估可行性，因为禁止重复使用讲师。 

最后，一个分段在覆盖计数方面可能看起来可行，但由于覆盖相同子范围的区间集中而仍然失败。 瓶颈不在于覆盖，而在于匹配能力。 

## 方法

 直接暴力方法固定一个段 [L, R]，然后尝试贪婪地或通过二分匹配来分配讲师。 每个起点有 n 个可能的左端点和 O(n) 个可能的右端点，因此有 O(n^2) 个段。 即使每个段的线性扫描也会导致 O(n^3)，并且即使每个段的优化匹配仍然太慢。 

关键的洞察力是翻转视角。 我们不测试线段，而是问：对于固定的右端点 R，使以 R 结尾的线段有效的最大 k 是多少，以及当我们移动 L 时，它会如何变化？ 

分段的可行性取决于我们是否可以选择覆盖 k 个不同日期的 k 个不同间隔。 这相当于检查对于该段的每个前缀，是否有足够的可用间隔延伸得足够远以覆盖该前缀。 此类问题的经典转换是通过右端点处理间隔并维护一个贪婪结构，该结构始终分配最早可能的未使用讲师。 

这变成了端点上的扫描线，并结合了一种结构，该结构始终可以检索仍然覆盖当前左边界的最早的可用整理间隔。 问题变成了维护间隔端点的活动多重集并在滑动窗口时模拟贪婪匹配。 

关键的减少是，对于每个左端点 L，我们可以确定最大 R，使得 [L, R] 可行。 一旦知道这一点，每个 k 都会通过计算有多少 L 满足 R = L + k − 1 来贡献。 

这导致对每个 L 计算贪婪分配下可到达的最远 R。 这是使用按正确端点排序的优先级队列有效计算的，始终消耗仍然到达当天的最小可用端点。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^3) | O(n^3) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 按左端点对所有区间进行排序。 这允许我们在扫描及时向前移动时激活间隔。 
2. 我们将从 1 到最大坐标迭代可能的起始点 L。 在每个 L 处，我们维护一组左端点 ≤ L 的活动区间。 
3. 维护由右端点作为键控的最小堆。 该堆代表当前可分配的所有讲师。 
4. 对于固定的 L，模拟从 L 开始贪婪地分配天数。 在 d 天，将所有 li ≤ d 的区间添加到堆中。 
5. 在每一天 d，从堆中删除所有右端点 < d 的间隔，因为它们不能再服务于 d 天。 如果堆变空，则从 L 开始的段将无法进一步扩展。 
6. 否则，选择一个间隔（具有最小右端点的间隔）并将其分配给第 d 天，然后将其从堆中删除，这样就无法重复使用。 
7. 继续此过程以找到最大可到达端点 R(L)。 段 [L, R(L)] 是从 L 开始的最长有效段。 
8. 最后，对于每个 L，将长度 R(L) − L + 1 的答案加 1。 

### 为什么它有效

 每天，选择具有最小右端点的间隔是最佳选择，因为它可以为未来几天保留灵活性。 任何具有较大右端点的区间只会减少未来的选项，而不会提高当前步骤的可行性。 这种贪婪的属性确保如果存在任何有效的分配，算法不会过早地阻止它。 因此，计算出的 R(L) 是从 L 开始存在完美分配的最大可能端点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n = int(input())
    intervals = []
    max_r = 0

    for _ in range(n):
        l, r = map(int, input().split())
        intervals.append((l, r))
        max_r = max(max_r, r)

    intervals.sort()

    ans = [0] * (n + 1)

    idx = 0
    heap = []

    for L in range(1, max_r + 1):
        while idx < n and intervals[idx][0] <= L:
            heapq.heappush(heap, intervals[idx][1])
            idx += 1

        if not heap:
            continue

        d = L
        local_heap = heap[:]
        heapq.heapify(local_heap)

        used = 0

        while True:
            while local_heap and local_heap[0] < d:
                heapq.heappop(local_heap)

            if not local_heap:
                break

            heapq.heappop(local_heap)
            used += 1
            d += 1

        ans[used] += 1

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```该实现遵循对 L 的扫描。对于每个 L，它构建活跃的间隔集，然后模拟向前的贪婪分配。 堆始终代表最佳的可用选择，删除过期的间隔可确保可行性检查的正确性。 

一个微妙的点是我们为每个 L 复制堆。这是必要的，因为贪婪模拟会消耗间隔，并且每个起点必须独立评估。 在完全优化的解决方案中，这种复制被持久性或可回滚的结构所取代，但通过这种方式更容易看出概念上的正确性。

 ## 边缘情况

 第一种边缘情况是所有区间都不相交。 对于 (1,1)、(2,2)、(3,3) 等输入，每个起始位置仅支持一天。 该算法仍然表现正确，因为在每个 L 处，堆仅包含一个可用间隔，并且它会立即被消耗，从而防止扩展。 

第二种边缘情况是所有间隔都相同，例如 (1,n) 的 n 个副本。 当 L=1 时，贪婪分配每天最多可以消耗 n 个间隔，产生长度为 n 的有效段。 基于堆的贪婪确保每个间隔仅使用一次，因此捕获最大扩展而不会过度计算重用。 

当间隔严重重叠但端点略有偏移时，会出现第三种边缘情况，例如 (1,3)、(2,4)、(3,5)。 贪心策略总是优先选择最小的右端点，这样可以避免后面的阻塞，并且这可以确保完整的链可以匹配。
