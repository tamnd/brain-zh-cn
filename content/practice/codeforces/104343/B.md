 ## 解决方案
 ## 问题理解

 我们得到了一组在特定时刻发生的事件。 每个事件对应于一个垂直向平面移动的点。 当点到达平面时，它在该平面中的水平位置是固定的，从那一刻起，它可以被认为在平面上是“活动的”。 

在任何时刻，平面上都有一条以原点为中心的旋转无限直线。 最初，这条线位于正 x 轴上，随着时间的推移，它可以顺时针或逆时针旋转。 唯一的限制是它的旋转速度：它的角速度受到我们选择的某个值 K 的限制。 

如果在事件在平面中变得活跃的确切时刻，旋转线通过该点（直到非常小的公差），则事件被成功“击中”。 由于线穿过原点，因此该条件相当于线的方向与从原点到该点的方向相匹配，最多 180 度翻转，因为线没有方向。 

因此，每个点都会贡献一个可用的特定时间以及可以击中该点的平面中的两个对称有效角度。 任务是确定最小角速度 K，使得线可以随着时间的推移以连续的方式旋转，遵守速度限制，并且仍然至少满足 M 个这些事件。 

约束 N ≤ 500 表示 O(N²) 或 O(N² log N) 方法是可以接受的，而如果与二分搜索相结合，则必须避免每次可行性检查出现立方或更差的情况。 这强烈表明我们可能会使用二次动态规划结构来测试 K 的候选值并验证可行性。 

当事件时间接近但需要大角度运动时，就会出现一个微妙的问题。 如果在短时间内两次所需的命中要求方向相互冲突，则小 K 将失败。 另一种故障模式是假设每个事件都可以独立处理，这忽略了线路必须在事件时间之间连续移动的事实。 

一个天真的错误是假设我们只需要根据某些瞬时角度的可行性单独检查每个事件。 例如，即使每个事件都可以单独到达，它们的顺序也可能迫使线路在连续选择的命中之间旋转得太快。 这使得该问题从根本上成为全局调度问题而不是逐点检查问题。 

另一个极端情况是当 M 很小时，但最佳兼容链不仅仅是按时间顺序排列的前 M 个事件。 顺序和角度兼容性相互作用，因此仅按时间或按角度的贪婪选择可能会失败。 

## 方法

 一个蛮力的想法是尝试选择 M 点的每个子集，并检查是否存在满足它们的连续旋转时间表。 对于固定的子集，我们还需要为每个点分配其两个有效角度之一，然后验证连续选定的点之间的角运动是否可以在速度 K 下实现。这导致子集的数量呈指数级增长，甚至检查一个子集也需要排序和约束验证。 当N达到500时，这是完全不可行的。 

关键的观察是，一旦我们按时间固定了所选点的顺序，可行性条件就变成局部的：在两个连续选择的事件之间，线必须在可用时间窗口内从一个所选角度旋转到另一个角度。 该约束仅取决于这两个事件，而不取决于结构的其余部分。

这将问题简化为在由时间顺序和角度可行性定义的有向非循环结构中选择最长有效链。 对于固定的 K，我们按时间对事件进行排序，并使用动态编程计算最长链，其中如果所选角度变量之间的角度差最多为时间差的 K 倍，则允许从 i 到 j 的过渡。 

由于可行性在 K 中是单调的，因此我们可以二分查找允许长度至少为 M 的链的最小 K。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集 | O(2^N·N) | O(2^N·N) | O(N) | 太慢了 |
 | DP + 二分查找 | O(N² log R) | O(N² log R) | O(N) | 已接受 |

 ## 算法演练

 ### 步骤 1：将几何图形转换为角度和时间

 对于每个点，计算其到达平面的时间 t_i = Z_i / U_i。 还计算其方向角 θ_i = atan2(Y_i, X_i)。 由于直线是无向的，因此每个事件允许两个有效角度：θ_i 和 θ_i + π。 

这将问题转换为在时间线上选择事件，每个事件都有两种可能的角度状态。 

### 第 2 步：按时间对事件进行排序

 通过增加 t_i 对所有事件进行排序。 任何有效的命中序列都必须遵守此顺序，因为我们只能在某个点变为活动状态时命中该点。 

### 步骤 3：固定 K 的可行性检查

 对于候选角速度 K，我们检查是否可以构建至少包含 M 个事件的有效链。 

我们将 dp[i] 定义为在事件 i 处可以命中的最大事件数。 

### 步骤 4：转换规则

 对于每一对 i < j，我们考虑将 i 连接到 j。 我们尝试所有角度选择的组合（两个用于 i，两个用于 j）。 如果满足以下条件，则转换有效：

 |角度_i − 角度_j| ≤ K·(t_j − t_i)

 如果有效，我们可以更新 dp[j] = max(dp[j], dp[i] + 1)。 

这编码了这样一个事实：线路必须在可用时间内在这两个方向之间物理旋转。 

### 步骤 5：计算最佳链长度

 我们计算所有事件的 dp。 如果 max(dp[i]) ≥ M，则 K 就足够了。 

### 步骤 6：二分查找 K

 我们在足够大的范围内二分搜索 K。 上限可以选择为允许任意快速旋转的值； 实际上，1e7 或更高版本足以进行可行性测试。 每次检查的成本为 O(N²)。 

### 为什么它有效

 DP 不变量是 dp[i] 存储在旋转约束下以 i 结束的最佳可能有效链。 任何有效的链都必须遵守时间顺序，因此有效解决方案的每个前缀也是有效的并出现在 DP 状态空间中。 转换条件精确地强制连续选择的命中之间的物理可达性，因此不能构造无效链，并且可以通过某些转换序列重建每个有效链。 

## Python 解决方案```python
import sys
import math
input = sys.stdin.readline

def can(K, pts, M):
    n = len(pts)
    dp = [1] * n
    
    for i in range(n):
        xi, yi, ti = pts[i]
        ai = math.atan2(yi, xi)
        ai2 = ai + math.pi
        
        for j in range(i + 1, n):
            xj, yj, tj = pts[j]
            dt = tj - ti
            if dt < 0:
                continue
            
            aj = math.atan2(yj, xj)
            aj2 = aj + math.pi
            
            best = dp[j]
            
            for a in (ai, ai2):
                for b in (aj, aj2):
                    diff = abs(a - b)
                    diff = min(diff, 2 * math.pi - diff)
                    if diff <= K * dt + 1e-12:
                        best = max(best, dp[i] + 1)
                        break
            
            dp[j] = best
    
    return max(dp) >= M

def solve():
    n, m = map(int, input().split())
    pts = []
    
    for _ in range(n):
        x, y, z, u = map(int, input().split())
        t = z / u
        pts.append((x, y, t))
    
    pts.sort(key=lambda p: p[2])
    
    if m == 1:
        print(0.0)
        return
    
    lo, hi = 0.0, 1e7
    
    ans = -1
    for _ in range(60):
        mid = (lo + hi) / 2
        if can(mid, pts, m):
            ans = mid
            hi = mid
        else:
            lo = mid
    
    if ans < 0:
        print(-1)
    else:
        print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```该解决方案首先将每个点转换为时间和角度对，然后按时间排序，以便所有转换都及时向前移动。 可行性检查使用动态编程构建最长的兼容序列，在角速度约束下测试所有有效的成对转换。 最后，二分查找收紧最小 K。 

一个微妙的实现细节是处理角度环绕。 由于角度是圆形的，因此必须使用直接差的最小值及其在 2π 附近的补数来计算差值。 

二分查找是稳定的，因为可行性是单调的：增加 K 只会放松约束。 

## 工作示例

 ### 示例 1

 我们计算时间并按到达时间对点进行排序。 然后我们测试增加 K。对于足够大的 K，每个转换都变得可行，允许所有 5 个点被链接起来。 

| 步骤| 活动我 | dp[i] | dp[i] | 原因 |
 | ---| ---| ---| ---|
 | 初始化| 全部 | 1 | 每个点单独|
 | 过渡| 多个| 增加| 所有对在 K = 90 时兼容 |

 最终链达到长度 5，因此 K = 90 就足够了。 

这表明当点在角度上分布良好时，约束纯粹是关于时间间隙之间的旋转速度。 

### 示例 2

 这里只存在 2 点，并且必须两者都取。 它们的角度间隔适中，并且时间足够接近，旋转约束很紧。 

| 步骤| 活动我 | 事件 j | dt | 角度差| 可行|
 | ---| ---| ---| ---| ---| ---|
 | 检查 | 1 | 2 | 小| 中等| 仅高于阈值 K |

 这证明了核心依赖性：即使只有两个点，K 也是由角距离随时间差确定的。

 ## 边缘情况

 一个关键的边缘情况是当两个点到达的时间非常接近但需要几乎相反的方向时。 在这种情况下，所需的 K 变得非常大，并且 DP 仅在时间差足以吸收角度跳变时才允许过渡。 

另一种情况是多个点共享相同的到达时间。 由于 dt 变为零，因此只有具有相同有效角度的对才能链接； 否则，无论 K 是多少，转换都是无效的，因为没有时间进行旋转。 

最后，M = 1 的情况总是返回零，因为根本不需要旋转，并且线已经以固定角度开始。
