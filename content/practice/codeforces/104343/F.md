 ## 解决方案
 ## 问题理解

 我们得到一个非常长的十进制字符串，表示一个数字，并且允许我们逐位修改它。 每次修改都意味着在字符串中选择一个位置，并将其数字替换为 0 到 9 之间的任何其他数字。数字的长度永远不会改变，因此我们本质上是在使用固定长度的数字数组。 

我们的目标是将原始数字转换为可被给定整数整除的新数字$M$。 我们可以自由地引入前导零，因此字符串应该被视为固定宽度的表示形式而不是传统的整数。 转换的成本是最终数字与原始数字不同的位置数，我们希望最小化这一成本。 

关键的困难来自于数字的大小：最多 200 万位数字。 这立即排除了任何尝试显式构造候选数字或直接模拟所有修改的方法。 即使以嵌套方式重复触摸所有数字也是不可能的。 任何可行的解决方案都必须将输入视为流，并避免与字符串长度成比例的每个状态重新计算。 

一个微妙的边缘情况是允许使用前导零。 这打破了人们对“数字”的通常直觉，迫使我们将问题视为具有模算术约束的纯字符串转换问题，而不是具有规范表示的标准整数DP。 

另一个重要的边缘情况是当$M = 1$。 在这种情况下，任何数字都是有效的，并且无论输入如何，答案都为零。 仍然执行大量 DP 的简单实现可能会不必要地进行 TLE。 

## 方法

 蛮力视角会尝试考虑所有可能的相同长度的字符串并计算它们是否可以被整除$M$。 对于每个候选字符串，我们将其与原始字符串进行比较并计算数字差异。 这显然是不可行的，因为字符串的数量是$10^n$，即使对于中等$n$。 

一个不太天真的想法是对前缀进行动态编程：我们逐位构建数字并跟踪余数模$M$。 在每个位置，我们尝试所有 10 位数字选择并更新其余部分。 这已经给出了大小的状态空间$O(nM)$，这对于$M \le 5000$，但完全不可能$n = 2 \cdot 10^6$。 

关键的观察是我们实际上不需要独立地探索所有前缀。 相反，我们将这个过程视为通过分层图寻找路径：每个位置贡献一个数字，并且转换更新其余部分。 如果选择一个数字与原始数字匹配，则选择该数字的成本为 0，否则为 1。 这成为图上的最短路径问题$n \times M$结构。 

然而，直接在该图上运行 Dijkstra 在时间和内存上都太大。 关键的简化来自于注意到转换仅取决于当前余数和下一个数字，并且边权重仅为 0 或 1。这使我们能够用每个位置 0-1 BFS 层处理来替换 Dijkstra，仅保持每个余数的最佳成本。 

我们从左到右处理字符串。 每一步我们维护一个数组`dist[r]`，表示达到余数所需的最少更改次数`r`到目前为止处理完前缀后。 对于每个新的数字位置，我们通过尝试所有数字替换并更新余数来计算一个新的数组。 成本更新是每个数字选择的恒定时间，因此每个位置的成本$O(10M)$，在给定约束的情况下这是可以接受的。 

这是有效的，因为我们永远不需要记住完整的数字历史，只需要记住前缀如何贡献模余数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对所有数字进行暴力破解 | O(10^n) | O(10^n) | O(n) | 太慢了 |
 | DP 位置和余数 | O(nM) | O(nM) | 对于 max n | 来说太慢了
 | 优化的滚动余量 DP | O(nM) | O(M)| 已接受 |

 ## 算法演练

 1.初始化一个距离数组`dist`尺寸的$M$， 在哪里`dist[r]`代表实现余数所需的最小变化$r$处理一些前缀后。 将所有值设置为无穷大，除了`dist[0] = 0`。 这对应于处理了空前缀。 
2. 从左到右，逐个位置地处理数字。 在位置$i$，我们考虑原始数字的当前数字，表示为$d$。 
3. 创建一个新数组`ndist`用大值初始化。 这将存储合并数字后的最佳成本$i$。 
4. 对于每一个可能的前余数$r$，我们尝试用每个数字替换当前数字$x \in [0,9]$。 新的余数变为$(r \cdot 10 + x) \bmod M$。 
5. 计算转换成本：如果$x = d$，成本为0，否则为1。更新`ndist[new_r] = min(ndist[new_r], dist[r] + cost)`。 
6. 处理完所有数字后$x$对于所有余数$r$， 代替`dist`和`ndist`。 
7. 处理完所有位置后，答案为`dist[0]`，因为余数 0 表示能被$M$。 

这种方法之所以高效，是因为每一层仅依赖于前一层，因此我们从不存储完整的历史记录。 DP 将整个字符串压缩为剩余部分的滚动状态。 

### 为什么它有效

 在任意前缀长度下，`dist[r]`表示构建产生余数的前缀所需的最少编辑次数$r$。 每个转换都保持正确性，因为它考虑当前位置的所有可能的数字选择并正确更新模块化状态。 由于每个完整的解决方案都对应于通过这些层的一条路径，并且每个路径成本只计算一次，因此最终的结果`dist[0]`必须等于数字变化的最佳数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    s = input().strip()
    m = int(input().strip())

    if m == 1:
        print(0)
        return

    dist = [INF] * m
    dist[0] = 0

    for ch in s:
        d = ord(ch) - 48
        ndist = [INF] * m

        for r in range(m):
            if dist[r] == INF:
                continue

            base = dist[r]

            for x in range(10):
                nr = (r * 10 + x) % m
                cost = base + (0 if x == d else 1)
                if cost < ndist[nr]:
                    ndist[nr] = cost

        dist = ndist

    print(dist[0])

if __name__ == "__main__":
    solve()
```代码直接遵循分层动态规划结构。 数字 0 到 9 上的内部循环表示尝试当前字符的所有可能替换。 余数转换`(r * 10 + x) % m`编码以 10 为基数附加一个数字。成本比较强制只有不匹配的数字才能得出答案。 

一个小但重要的实现细节是跳过状态`dist[r]`是无穷大，这避免了不必要的工作。 如果没有这种修剪，内部循环仍然是正确的，但速度明显慢。

 ## 边缘情况

 一种边缘情况是当输入数字已被整除时$M$。 在这种情况下，DP 开始于`dist[0] = 0`并且永远不会找到一条更便宜的路径来不必要地更改数字，因此最终答案仍然为零。 

另一种情况是当$M = 1$。 每个数字都是有效的，因此算法会立即返回零，而不执行 DP，从而避免了对大字符串进行不必要的计算。 

最后一个微妙的情况是必须更改所有数字以实现整除性。 DP 仍然可以正确处理这个问题，因为它始终考虑每个位置的所有数字 0 到 9，从而确保探索甚至完全不同的结构，并通过余数转换准确累积其成本。
