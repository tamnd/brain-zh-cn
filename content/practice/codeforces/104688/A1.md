 ## 解决方案
 ## 问题理解

 我们得到一个以通常的十进制形式书写的非负整数序列。 我们从左到右处理它们，我们的任务是转换序列，使其变得严格递增。 唯一允许的操作是获取一个数字并将十进制数字附加到其右侧。 每个附加数字都算作一次操作，因此将数字扩展三位需要花费三次操作。 

目标是最大限度地减少所需附加数字的总数，以便每个数字在最终形式中都严格大于前一个数字。 

一个关键的微妙之处是我们不允许在前进后修改早期的数字。 一旦我们决定如何扩展一个数字，它就成为后续比较的固定值。 这使得该过程本质上是贪婪的。 

这些约束足够大，以至于任何重复重建字符串或模拟逐位增量的二次或每次比较构造都会太慢。 预期的解决方案必须处理每个数字一次，并根据先前转换的数字进行本地推理，其工作时间与总位数成正比。 

一个常见的失败案例来自于错误地处理前缀关系。 考虑顺序`[12, 121]`。 简单的比较表明 121 大于 12，因此无需更改。 但是，一旦我们考虑到 12 可能已在前面的步骤中扩展，或者严格的递增顺序必须适用于转换后的值，我们就会看到，不考虑附加操作的简单数字比较会破坏不变量。 

另一个有问题的案例是`[100, 1]`。 简单地比较数字表明我们可以在后面附加零`1`要得到`10`,`100`等等，但如果不保证严格增而不减，盲目匹配长度仍然会失败。 

这些情况迫使我们仔细推理数字在附加情况下的行为以及如何最小化扩展数字以使其严格大于前一个数字。 

## 方法

 暴力策略会尝试所有可能的方法将数字附加到每个数字，直到序列严格递增。 对于每个位置，我们可能会尝试附加最大位数并递归地确保后缀保持有效。 由于每个数字都可以以多种方式增长，因此分支因子在位置数量上呈指数增长，甚至适度的输入大小也变得棘手。 

关键的观察是，一旦我们贪婪地修复它们，我们就永远不需要探索早期数字的多个候选形式。 在每一步中，只有之前转换的数字很重要，而不是完整的历史记录。 问题简化为：将先前的结果数字作为字符串，最小限度地扩展当前数字，使其变得严格更大。 

实现效率的结构是数字扩展下的字典比较。 我们不将数字视为整数，而是将它们视为字符串，并推理附加数字如何影响排序。 

最佳方法将当前字符串与前一个字符串进行比较，并决定是否附加零、匹配前缀或稍微超出前缀边界。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了|
 | 贪婪字符串扩展 | O(总位数) | 每步额外 O(1) | 已接受 |

 ## 算法演练

 我们维护一个变量`prev`，它将前一个数字的最终形式存储为字符串。 

对于每个新号码`cur`，我们尝试构造严格大于的最小可能字符串`prev`仅使用数字附加。 

1. 转换`cur`和`prev`成字符串。 让`s = cur`,`t = prev`。 
2.如果`len(s) > len(t)`， 然后`s`长度可能已经足够大。 如果`s > t`，我们保持不变。 否则，我们附加一个`'0'`到`s`。 这保证了它变得更大，因为增加长度总是会增加相对于固定长度的先前数字的幅度。 
3.如果`len(s) == len(t)`，我们直接比较它们。 如果`s > t`，我们接受它。 否则，我们附加一个`'0'`强制增加长度，这保证了严格增加。 
4. 如果`len(s) < len(t)`，我们尝试对齐`s`和`t`通过使用前缀推理。 让`k = len(s)`。 

我们检查前缀`t[:k]`。 

如果`s < t[:k]`，那么无论我们如何延伸，最终都必须达到长度`len(t)`超越`t`。 所以我们准确地附加`len(t) - k`零。 

如果`s > t[:k]`，我们再次追加`len(t) - k`零，因为匹配长度足以使其大于`t`。 

微妙的情况是当`s == t[:k]`。 这里我们尝试模仿`t`进一步附加`t[k:]`。 如果此扩展仍然产生大于`t`，我们完成了。 如果它只是匹配或由于尾随 9 或完全相等而未能超过，我们会在长度之外再追加一位数字`len(t)`，确保严格增长。 
5.新建后`s`，我们计算附加了多少位数字并将其添加到答案中，然后设置`prev = s`。 

### 为什么它有效

 不变的是处理后的位置`i`,`prev`是变换后的最小可能的字符串表示`a[i]`满足前面所有元素的严格增加。 在每一步中，我们只考虑超出所需的最小扩展`prev`，任何较短的扩展都会违反顺序，而任何较长的扩展都会不必要地增加成本。 由于比较是基于前缀优势和以 10 为基数表示的长度效应，因此贪婪选择是局部最优的，并且保持全局最优。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = input().split()

    prev = a[0]
    ans = 0

    for i in range(1, n):
        s = a[i]
        t = prev

        if len(s) > len(t):
            if s > t:
                prev = s
            else:
                ans += 1
                prev = s + "0"
            continue

        if len(s) == len(t):
            if s > t:
                prev = s
            else:
                ans += 1
                prev = s + "0"
            continue

        k = len(s)
        if t[:k] != s:
            if s < t[:k]:
                add = len(t) - k
                ans += add
                prev = s + "0" * add
            else:
                add = len(t) - k
                ans += add
                prev = s + "0" * add
        else:
            tail = t[k:]
            candidate = s + tail
            if candidate > t:
                ans += len(t) - k
                prev = candidate
            else:
                add = len(t) - k + 1
                ans += add
                prev = s + "0" * add

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案将所有内容保留为字符串，以避免整数溢出并使数字级推理变得明确。 执行的唯一操作是比较、切片和串联，所有操作都与位数呈线性关系。 

一个微妙的实现细节是，每当我们完全匹配前缀时，我们都会尝试重用后缀`prev`。 这是我们可以避免添加额外数字的唯一情况，因为它可以产生一个最小的严格更大的数字，而无需直接跳转到下一个长度。

 ## 边缘情况

 当当前号码与前一个号码的前缀完全匹配时，就会出现一种重要的边缘情况。 例如，`prev = 12345`和`cur = 123`。 算法进入前缀匹配分支并尝试重用后缀`"45"`。 如果`12345`相对于此扩展名已经太大，正确的解决方法是在长度五之外附加一位额外的数字。 这确保我们移动到`1230000`，保证大于`12345`同时最大限度地减少操作。 

另一种情况是当所有数字`prev`前缀后面是零或九。 在这种情况下，尝试重用后缀可能会产生相等或无法超过，从而迫使算法进入附加数字的后备状态。 该结构仍然保证正确性，因为增加长度始终足以打破十进制比较中的平局。
