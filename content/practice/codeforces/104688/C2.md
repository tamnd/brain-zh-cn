 ## 问题理解

 我们得到的系统存在未知的起始值，但在“黑客”版本中我们实际上知道它。 除此之外，还有一个我们想要将其转换成的目标值。 唯一允许的工具是应用于当前值的一小组类似算术的运算：我们可以添加一个数字，乘以一个数字，除以一个数字，或者用数字的总和替换该数字。 每个操作都是按顺序应用的，我们必须生成一个简短的此类操作序列，以保证最终值完全等于目标。 

尽管交互描述看起来像是针对隐藏值的游戏，但黑客版本消除了不确定性，因此任务变得具有建设性：给定两个整数，我们必须显式编写一个简短的允许操作序列，将初始值转换为目标值。 

这些约束在与典型问题不同的意义上是严格的。 限制不是计算时间，而是操作数量，最多为四次。 这立即排除了任何逐渐从一个数字“行走”到另一个数字或模拟逐位构造的方法。 值之间的任何线性差异都是不可能的，因为如果天真地这样做，即使差异为 1，也已经需要超过允许的预算。 

朴素的算术策略出现了一个微妙的问题。 例如，直接对差异进行单次相加似乎很有吸引力，但它可能会违反此问题的其他变体中的约束，其中中间值必须保持有效或存在隐藏值。 另一个危险的想法是尝试分解差异并使用乘法和除法运算。 这会失败，因为数字的结构是任意的并且不能保证整除性。 

主要困难在于我们必须快速将任意值压缩为“结构化”的东西，然后在恒定数量的步骤内以受控方式重建目标。 

## 方法

 蛮力思维会尝试使用小增量或基于因子的调整来模拟从初始值到目标值的转换。 人们可以想象重复地添加或减去值或尝试通过类似 gcd 的操作来对齐数字。 这在原则上是正确的，因为这些操作的表达能力足以达到任何整数，但在严格的四次操作上限下是完全不可行的。 在最坏的情况下，达到较大的目标差异将需要线性或对数的许多步骤，这会立即超出限制。 

关键的观察结果是数字和运算作为压缩工具非常强大。 重复应用它会将 10^9 以内的任何数字折叠到一个非常小的范围内。 一个应用程序将数字减少到最多 81，第二个应用程序将其进一步减少到 1 到 9 之间的一位数。这一点至关重要，因为一旦该值处于有限范围内，我们就可以使用一次乘法和一次加法“重建”任何目标。 

这将问题分为两个阶段。 首先，我们使用数字和积极地将未知值减少为规范的小代表。 其次，我们使用一个缩放步骤和一个偏移校正从该代表构建目标。

 ## 算法演练

 我们假设我们知道初始值`x`和目标`n`。 

1. 应用一次数字和运算。 这取代了`x`通过其数字之和，这保证了该值最多变为 81。这一步是安全的，因为对于正整数，数字和永远不会产生零，因此我们始终保留可用的正状态。 
2. 再次应用数字和运算。 由于该值现在最多为 81，因此结果最多变为 9。在此步骤之后，当前值是 1 到 9 之间的单个数字。此步骤很重要，因为使用有界的单个数字基数允许使用最多两个操作来精确重建任何目标。 
3. 计算如何缩放这个小值以接近目标。 设当前值为`c`。 我们计算`q = n // c`。 乘以`q`将我们与最大的倍数对齐`c`不超过`n`。 这是有效的，因为允许乘法并使值保持在界限内。 
4. 应用乘法运算`q`，将值更新为`c * q`。 
5. 计算剩余差值`r = n - c * q`。 该余数保证小于`c`，因此很小。 然后我们应用一个加法运算`r`，这恰好带来了价值`n`。 

一个微妙的细节是所有算术都是以整数完成的，并且`c`永远不会为零，因此计算时除法始终有效`q`。 

### 为什么它有效

 正确性取决于两个数字和运算后的不变量，当前值是范围内的非零整数`[1, 9]`。 从这一点开始，每个整数`n`可以唯一地分解为`n = c * q + r`和`0 ≤ r < c`。 乘法步骤设置基本倍数，加法步骤精确校正余数。 由于这两个操作在约束下始终有效，因此最终值必须等于`n`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def digit_sum(x):
    return sum(map(int, str(x)))

def solve():
    t = int(input())
    for _ in range(t):
        # in hacked version: we read n and x
        n, x = map(int, input().split())
        
        ops = []
        
        # step 1: digit
        x = digit_sum(x)
        ops.append(("digit",))
        
        # step 2: digit again
        x = digit_sum(x)
        ops.append(("digit",))
        
        # now x is in [1, 9]
        c = x
        
        q = n // c
        r = n - c * q
        
        # step 3: multiply
        x = x * q
        ops.append(("mul", q))
        
        # step 4: add remainder
        x = x + r
        ops.append(("add", r))
        
        # output operations
        for op in ops:
            if op[0] == "digit":
                print("digit")
            else:
                print(op[0], op[1])

        # final check command (not needed in hack, but conceptually)
        print("!")

if __name__ == "__main__":
    solve()
```前两个操作将初始值压缩为一位数代表。 乘法步骤一次性将该代表扩展到目标，最后的加法确定了精确的偏移量。 顺序很重要，因为在乘法之前执行加法会使干净分解为基数和余数无效。 

一个常见的错误是尝试仅使用一位数字和。 这使得该值的范围最多为 81，并且重建变得不太稳定，因为余数可能超出单个校正步骤的允许范围。 第二个数字和保证了严格的 1 到 9 范围，并使分解始终安全。 

## 工作示例

 考虑一个例子，其中`n = 100`和`x = 987`。 

在第一个数字和之后，该值变为 9 + 8 + 7 = 24。 

第二个数字和之后，它变成 2 + 4 = 6。现在`c = 6`。 

我们计算`q = 100 // 6 = 16`和`r = 100 - 96 = 4`。 

相乘后，该值变为 96。相加后，该值变为 100。 

踪迹：

 | 步骤| 当前值| 运营|
 | --- | --- | --- |
 | 开始| 987 | 987 初始|
 | 1 | 24 | 数字|
 | 2 | 6 | 数字|
 | 3 | 96 | 96 乘16 |
 | 4 | 100 | 100 添加 4 |

 这显示了数字压缩如何创建允许精确重建的稳定基础。 

现在考虑第二个例子`n = 37`和`x = 12345`。 

数字和给出 15，第二个数字和给出 6，所以`c = 6`。 

我们计算`q = 6`,`r = 37 - 36 = 1`。 

乘法后得到 36，加法得到 37。 

| 步骤| 当前值| 运营|
 | --- | --- | --- |
 | 开始| 12345 | 初始|
 | 1 | 15 | 15 数字|
 | 2 | 6 | 数字|
 | 3 | 36 | 36 乘 6 |
 | 4 | 37 | 37 添加 1 |

 这两个例子都表明，一旦减少到一位数，构造就变得确定性。
