 ## 解决方案
 ## 问题理解

 给定一个整数数组，我们需要决定是否可以重新排序该数组，以便当我们从左到右连续应用模运算时，最终结果不为零。 形式上，我们想要一个排列$b_1, b_2, \dots, b_n$输入数组的$a_1, a_2, \dots, a_n$这样$$b_1 \bmod b_2 \bmod \dots \bmod b_n \neq 0$$模运算是左结合的，所以我们首先计算$b_1 \bmod b_2$，然后对该结果取模$b_3$， 等等。 例如，如果$b = [2024, 1000, 8]$，评价为$(2024 \bmod 1000) \bmod 8 = 24 \bmod 8 = 0$。 

输入包含多个测试用例。 每个测试用例指定元素数量$n$和数组本身。 约束允许最多$10^4$测试用例和总共$2 \cdot 10^5$所有测试用例中的元素。 这排除了任何比粗略更糟糕的解决方案$O(n \log n)$每个测试用例，如$O(n^2)$解决方案将超过时间限制。 

当数组包含所有相同的数字时，就会出现微妙的情况。 例如，$[3, 3, 3]$无论排列如何，它的值总是为零，因为任何数字模本身都是零，而零模任何东西都保持为零。 另一个棘手的情况是当数组中的最小数字是$1$。 如果$1$首先出现的结果是$1 \bmod x$总是$1$，在后续的模运算中不能减为零。 所以存在一个$1$如果安排正确，可以保证非零结果。 

## 方法

 蛮力方法是尝试所有$n!$数组的排列并计算每个排列的链式模数。 这显然是不可行的，因为$n$可以达到$10^5$。 即使尝试在开始时只考虑最小元素的排列，对于较大的数组来说仍然会产生组合爆炸性的后果。 

关键的见解是左关联模运算对大数和小数的顺序敏感。 具体来说，第一个元素确定最大起始余数。 如果我们将最大的元素放在前面，将最小的元素放在最后，我们就可以最大化中间余数不会过早达到零的机会。 我们注意到，如果在某个步骤中当前余数是下一个数字的倍数，则该操作只能产生零。 因此，如果我们以非降序对数组进行排序，则第一个模运算是$a_1 \bmod a_2$。 如果$a_1 < a_2$，余数为$a_1$，它是非零的。 通过保持数字不减，我们确保余数永远不会立即归零，除非所有数字都相同。 

因此，解决方案简化为检查数组是否包含多个不同的值。 如果所有元素都相等，则答案为“否”。 否则，以非降序对数组进行排序可保证链式模的计算结果为非零值。

 ## 算法演练

 1. 对于每个测试用例，读取元素数量$n$和数组$a$。 
2. 检查所有元素是否在$a$是平等的。 如果是，则输出“NO”，因为任何排列都会产生零。 
3. 否则，按非降序对数组进行排序。 这确保了第一个模运算是安全的，并且余数不会过早崩溃为零。 
4. 输出“YES”表示存在有效排列。 我们不需要实际构建这个问题的排列，只需确认它的存在即可。 

为什么它有效：不变的是，如果数组包含至少两个不同的数字，则以非递减顺序排列它们可确保每次模运算后的余数被保留或减少，但永远不会立即为零，除非在全相等的情况下。 由于最小的数字位于序列的前面或早期，因此左关联模链不能将其减少到零，除非所有数字都相等。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    if len(set(a)) == 1:
        print("NO")
    else:
        print("YES")
```代码首先读取测试用例的数量。 对于每个测试用例，它读取数组并将其转换为一个集合以计算不同元素的数量。 如果只有一个不同的元素，则打印“NO”。 否则，它会打印“YES”。 使用`set(a)`至关重要，因为它可以有效地处理具有重复元素的数组。 如果我们只关心存在的话，排序其实是没有必要的。

 ## 边缘情况

 具有所有相同数字的数组由`set(a)`查看。 处理仅具有两个不同数字的数组，因为至少一个模运算将产生非零余数。 数组中最小的数字是`1`自然会被处理，因为首先放置它可以保证模链保持非零。 具有大数字的数组是安全的，因为 Python 本身就可以处理大整数。 该算法不依赖于构造实际的排列，仅依赖于具有至少两个不同数字的属性。
