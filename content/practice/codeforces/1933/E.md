 ## 解决方案
 ## 问题理解

 我们被要求对艾萨克在多个跑道上的训练进行建模。 每条赛道都由许多等长的部分组成，完成的每个部分都会以线性递减的方式提高他的表现。 第一部分贡献`u`，第二个`u-1`，第三个`u-2`， 等等。 这意味着如果艾萨克完成的部分多于`u`，某些部分甚至可能会降低他的表现，因为增量变为负值。 

对于给定的起始轨道`l`和价值`u`，我们必须选择一个结尾曲目`r`（在哪里`l ≤ r ≤ n`）以最大化总性能增益。 如果有多个`r`产生相同的最大增益，则选择最小的。 每个查询提供不同的`l`和`u`，并且我们有多个测试用例。 

约束条件表明`n`和`q`每个可以达到`10^5`每个测试用例，但所有测试用例的总数不超过`2 * 10^5`。 尝试所有可能的天真的方法`r`对于每个查询可能需要`O(n * q)`时间，可以达到`10^{10}`在最坏的情况下，显然速度太慢。 我们需要一种使用预计算以对数或接近恒定的时间处理每个查询的方法。 

棘手的部分包括当总部分超过时处理负增量`u`，并且关系多个`r`值给出相同的总增益。 直接对每个候选人的增量求和的粗心实现`r`可能会产生错误的答案或超出时间限制。 

具体的边缘情况是`u`小于以下部分的总和`l`到`n`。 例如，如果`a = [2, 2, 2]`和`l = 1, u = 2`，完成所有曲目给出部分`[2,2,2]`总计 6。性能增量为`2,1,0,-1,-2,-3`，因此最大增益出现在完成所有部分之前。 总是将所有部分相加的幼稚方法会被选择`r=3`错误地。 

## 方法

 暴力法计算每种可能的总性能增益`r`开始于`l`。 对于每个`r`，我们将之间的所有部分相加`l`和`r`确定我们采取多少增量，然后求和`u, u-1, ..., u-(total_sections-1)`。 这适用于正确性，但对于大`n`和许多查询变得不切实际，因为内部循环可以运行`O(n)`对于每个查询，结果是`O(n*q)`运营。 

关键的见解是预先计算轨道部分的前缀和。 让`prefix[i]`是第一个的总和`i`曲目。 那么总节数为`l`到`r`是`prefix[r] - prefix[l-1]`。 总增益为`S`以 value 开头的部分`u`可以使用算术级数公式计算：`u + (u-1) + ... + (u-S+1) = S*u - S*(S-1)//2`。 一旦前缀和准备好，这使我们能够在 O(1) 时间内计算任何连续子数组的增益。 

由于增益函数`G(S) = S*u - S*(S-1)/2`是一个凹二次方程`S`，增益增加，同时`S ≤ u`并减少时`S > u`。 因此，为了最大化增益，我们需要找到最小的`r`这样总部分来自`l`到`r`刚好高于或等于`u`。 这可以通过对前缀和进行二分搜索来有效地完成。 对于每个查询，我们计算`target = prefix[l-1] + u`并寻找最小的`r ≥ l`这样`prefix[r] ≥ target`。 如果`prefix[n] < target`，我们选择`r = n`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n*q) | O(n*q) | O(n) | 太慢了 |
 | 前缀和+二分查找| O(n + q*log n) | O(n + q*log n) | O(n) | 已接受 |

 ## 算法演练

 1. 预先计算各轨道段的前缀和。 让`prefix[0] = 0`和`prefix[i] = prefix[i-1] + a[i-1]`。 这允许 O(1) 计算任意之间的总部分`l`和`r`。 
2. 对于每个查询`(l, u)`， 定义`current_prefix = prefix[l-1]`。 我们想要总部分`S = prefix[r] - current_prefix`尽可能接近`u`尽可能不超过最大增益。 如果`S <= u`，增益随着节数的增加而增加； 如果`S > u`，增益开始减小。 
3. 对前缀和数组执行二分查找`r = l`到`n`找到最小的`r`这样`prefix[r] - prefix[l-1] ≥ u`。 如果没有这样的`r`存在，选择`r = n`。 
4.输出这个`r`作为查询的答案。 通过建设，这`r`提供最大的性能增益，因为它收集尽可能多的部分而不超过`u`以一种会减少增益的方式。 

原理：算术级数增益公式是凹的。 因此，一旦节数超过`u`，附加部分会降低总增益。 二分查找保证第一`r`达到最高增益，满足问题要求选择最小`r`如果有关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        prefix = [0] * (n + 1)
        for i in range(1, n+1):
            prefix[i] = prefix[i-1] + a[i-1]
        q = int(input())
        queries = [tuple(map(int, input().split())) for _ in range(q)]
        res = []
        for l, u in queries:
            # binary search for smallest r such that prefix[r] - prefix[l-1] >= u
            low, high = l, n
            ans = n
            target = prefix[l-1] + u
            while low <= high:
                mid = (low + high) // 2
                if prefix[mid] >= target:
                    ans = mid
                    high = mid - 1
                else:
                    low = mid + 1
            res.append(ans)
        print(' '.join(map(str, res)))

if __name__ == "__main__":
    solve()
```该解决方案首先计算每个测试用例的前缀和。 然后使用二分搜索独立处理每个查询，以找到累积节数达到或超过的第一个轨道`u`。 目标调整为`prefix[l-1]`因为计数是从轨道开始的`l`。 这可以正确处理相差一的问题并确保最小`r`被选中。 使用`prefix[n]`作为上限保证如果`u`大于剩余部分的总和，`r = n`被选中。 

## 工作示例

 示例 1 第一个查询：`l = 1, u = 8`, 曲目`a = [3,1,4,1,5,9]`。 

| r | 前缀[r]-前缀[l-1] | 增益公式| 决定|
 | --- | --- | --- | --- |
 | 1 | 3 | 8+7+6 = 21 | 小于你|
 | 2 | 4 | 8+7+6+5 = 26 | 小于你|
 | 3 | 8 | 8+7+6+5+4+3+2+1 = 36 | 等于你|
 | 4 | 9 | 8+7+6+5+4+3+2+1+0 = 36 | 增益相同，r | 不更小

 这证实了算法正确地选择了第一个`r`达到最大增益。
