 ## 解决方案
 ## 问题理解

 我们有两种晶体可供选择：黄色和蓝色。 

生产每种类型的球都会消耗固定配方的水晶。 黄色球需要 2 个黄色水晶。 绿球需要 1 个黄水晶和 1 个蓝水晶。 一个蓝色球需要 3 个蓝色水晶。 

输入给出黄色晶体的当前库存`A`和蓝色水晶`B`，然后是所需的黄色、绿色和蓝色球的数量：`x`,`y`， 和`z`。 

我们的任务是确定必须购买多少额外的晶体，以便可以生产所有要求的球。 我们可以自由购买黄色和蓝色水晶，并且我们想要额外水晶的总数最少。 

约束条件达到$10^9$。 这些值立即排除了任何逐一创建球或重复减去晶体的模拟。 即使是球数量的线性算法也太慢了。 由于输入仅包含五个整数，因此我们应该期望得到一个恒定时间的算术解决方案。 

一个常见的错误是单独处理每种球类型的短缺，而不是首先计算总的晶体需求。 

考虑：```
A = 2, B = 1
x = 1, y = 1, z = 0
```所需的黄色晶体是$2 \cdot 1 + 1 = 3$。 所需的蓝水晶是$1$。 

我们正好缺一颗黄水晶，所以答案是`1`。 

单独检查每个球配方的粗心方法可能会重复计算短缺情况。 

另一个容易犯的错误是从总需求中减去可用的晶体，并允许负赤字来减少答案。 

例子：```
A = 100, B = 0
x = 1, y = 0, z = 0
```只需要 2 个黄色晶体。 多余的98颗黄水晶无法弥补其他情况下缺失的蓝水晶。 每种颜色必须独立处理。 这里正确的额外金额是`0`，不是负数。 

当一种颜色有剩余而另一种颜色有短缺时，就会出现最后的边缘情况。```
A = 10, B = 1
x = 0, y = 0, z = 1
```我们需要 3 个蓝色水晶，但只有 1 个。答案是`2`，尽管黄色晶体丰富。 水晶颜色不可互换。 

## 方法

 最直接的想法就是考虑将每一个要求的球都一一制作出来。 对于每个黄色球，我们将消耗两颗黄色水晶，对于每个绿色球，我们将消耗一颗黄色水晶和一颗蓝色水晶，对于每个蓝色球，我们将消耗三颗蓝色水晶。 如果水晶用完，我们会计算还需要购买多少水晶。 

这种方法是正确的，因为它完全遵循食谱。 问题是球的数量可以达到$10^9$。 模拟每个球需要数十亿次操作，这在时间限制内是不可能的。 

关键的观察结果是生产顺序并不重要。 每个黄色球总是消耗 2 个黄色水晶。 每个绿球总是消耗 1 个黄水晶和 1 个蓝水晶。 每个蓝色球总是消耗 3 个蓝色水晶。 

我们可以直接计算总晶体需求，而不是模拟生产。 

所需的黄色晶体总数为：$$2x + y$$总共需要的蓝色晶体是：$$y + 3z$$一旦知道这些总数，我们就会将其与可用供应量进行比较。 

如果所需的黄色晶体超过`A`，我们必须买差价。 否则我们什么也不买。 同样的逻辑也适用于蓝色晶体。 

答案很简单，就是两个短缺的总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(x + y + z) | O(x + y + z) | O(1) | O(1) | 太慢了|
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取可用的黄色和蓝色晶体，`A`和`B`。 
2. 读出所需的黄、绿、蓝球的数量，`x`,`y`， 和`z`。 
3. 计算所需的黄色晶体总数为`2 * x + y`。 

每个黄色球贡献 2 个黄色水晶，每个绿色球贡献 1 个黄色水晶。 
4. 计算所需的蓝色晶体总数为`y + 3 * z`。 

每个绿色球贡献 1 个蓝色水晶，每个蓝色球贡献 3 个蓝色水晶。 
5. 将黄色短缺计算为`max(0, needed_yellow - A)`。 

如果我们已经有足够的黄水晶，那么短缺量应该是零而不是负数。 
6. Compute the blue shortage as`max(0, needed_blue - B)`。 
7. 输出两个短缺之和。 

### 为什么它有效

 配方准确地确定了每个请求的球消耗了多少黄色和蓝色水晶。 添加这些贡献就得出了每种晶体颜色的独特总要求。 

黄水晶只能满足黄色要求，蓝水晶只能满足蓝色要求。 因为两种颜色是独立的，所以最少添加的晶体数量就是缺少的黄色晶体和缺少的蓝色晶体的总和。 一种颜色的任何过剩都不能减少另一种颜色的短缺。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    A, B = map(int, input().split())
    x, y, z = map(int, input().split())

    needed_yellow = 2 * x + y
    needed_blue = y + 3 * z

    answer = max(0, needed_yellow - A) + max(0, needed_blue - B)
    print(answer)

solve()
```前两行读取可用的晶体数量和请求的球数。 

变量`needed_yellow`和`needed_blue`存储直接从配方中得出的总水晶需求量。 这避免了任何模拟。 

致电`max(0, ...)`是至关重要的。 如果我们已经有足够的某种颜色的晶体，那么该颜色对答案的贡献为零。 此处允许负值会错误地让一种颜色的剩余减少总数。 

Python 整数会自动处理大于 32 位限制的值，尽管即使在具有固定大小整数的语言中，最大的表达式也只有几十亿，并且适合 64 位类型。

 ## 边缘情况

 考虑不涉及晶体和球的情况：```
0 0
0 0 0
```该算法计算：```
needed_yellow = 0
needed_blue = 0
```两者的短缺都为零，因此产量为：```
0
```这证实了该公式正确处理空需求。 

考虑一种颜色有剩余的情况：```
10 1
0 0 1
```该算法计算：```
needed_yellow = 0
needed_blue = 3
```短缺情况变成：```
yellow = max(0, 0 - 10) = 0
blue = max(0, 3 - 1) = 2
```输出是：```
2
```多余的黄色晶体将被忽略，因为晶体颜色无法交换。 

考虑一种完全满足一个要求的情况：```
5 4
2 1 1
```该算法计算：```
needed_yellow = 5
needed_blue = 4
```短缺的情况是：```
yellow = 0
blue = 0
```输出是：```
0
```这验证了平等处理是否正确，并且不会产生不必要的购买。 

最后，考虑：```
2 1
1 1 0
```要求是：```
needed_yellow = 3
needed_blue = 1
```短缺的情况是：```
yellow = 1
blue = 0
```答案是：```
1
```这说明了为什么必须独立计算每种颜色的短缺情况。 黄色晶体的不足不能用蓝色晶体来弥补。
