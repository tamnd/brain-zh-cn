 ## 解决方案
 ## 问题理解

 我们被要求枚举一组非常具体的整数，然后从该有序列表中选择一个特定元素。 允许的数字是那些素数因子全部来自给定素数的固定小集合的数。 换句话说，每个有效数字都可以写成仅提供的素数的幂的乘积，并且不允许在其因式分解中出现其他素数。 

该序列从 1 开始按递增顺序考虑，因为 1 没有素因数并且在此定义下始终有效。 任务是找到这个无限递增序列中的第 k 个元素。 

这些约束以强有力的方式塑造解决方案空间。 允许的素数数量最多为 16，这排除了任何尝试以朴素指数方式在所有值上显式组合所有素数子集的方法。 然而，素数本身的值很小，并且答案保证最多为 10^18，这使我们能够根据数字搜索而不是所有可能性的组合生成来进行推理。 隐藏的结构是，虽然序列的长度是无限的，但是它的值却是稀疏且单调的。 

微妙的边缘情况立即出现在序列的开头。 数字 1 必须作为第一个元素包含在内。 任何直接从素数开始生成并忽略 1 的实现都会减少 1。 另一个问题来自重复生成。 如果我们不小心的话，像 12 = 2^2 * 3 这样的数字可以通过多个乘法路径产生，因此，除非我们强制排序，否则自由排列素数的朴素 DFS 将会计数过多。 

## 方法

 一种直接的方法是使用最小堆以递增的顺序生成数字，反复将发现的数字乘以每个素数并将结果推回。 这类似于生成“丑陋的数字”。 当 k 很小时，这很有效，但这里 k 的大小没有限制，并且它可能非常大，而实际答案值仍保持在 10^18 以内。 基于堆的方法需要 k 次插入和 log k 次操作，当 k 很大时，这变得不可行。 

关键的观察结果是我们实际上不需要构建直到索引 k 的序列。 我们只需要确定哪个值是第 k 个最小的，并且我们得到了答案值的严格界限。 这表明我们要扭转视角：我们不是通过索引生成序列，而是测试候选值并询问有多少个有效数字 ≤ x。 这会将问题转换为单调计数函数，从而实现对答案的二分搜索。 

剩下的困难是有效计算 ≤ x 的有效数字的数量。 因为 n ≤ 16，我们可以对素数进行深度优先枚举，构造乘积，同时强制使用非递减素数索引以避免重复。 每个状态都会将当前值乘以选定的素数，并且只要乘积保持在限制范围内就继续下去。 这会生成每个有效数字一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | Heap generation | O(k log k) | O(k) | 太慢了|
 | 二分查找+DFS计数| O(log V · S) | O(depth) | 已接受 |

 这里V最大为10^18，S是剪枝下生成的状态数。 

## 算法演练

 我们通过对答案的值进行二分查找并使用计数过程来测试可行性来解决问题。 

1. Define a function`count(x)`返回有多少个有效数字 ≤ x。 

该函数包括 1 和给定素数的所有乘积，其值不超过 x。 
2. 实施`count(x)`对素数使用深度优先搜索。 

我们从值 1 开始，每一步乘以索引不小于当前索引的素数。 

这种排序可以防止通过质因数的不同排列生成相同的数字。 
3. 在DFS中，只要当前值≤x，就被视为有效数。 

然后，我们通过与符合条件的素数相乘来继续扩展它，当乘积超过 x 时停止。 
4. 对答案空间从 1 到 10^18 进行二分查找。 

对于每个中点 mid，计算`count(mid)`。 

如果计数至少为 k，我们就知道答案位于中值或以下，否则答案位于中值以上。 
5、二分查找收敛后，输出其中的最小值`count(value) ≥ k`。 

正确性取决于计数函数的单调性：如果 x 增加，则有效数字 ≤ x 的集合只能增长。 

### 为什么它有效

 每个有效数字都有一个唯一的表示形式，即给定素数与非负指数的乘积。 通过强制我们仅使用当前索引处或之后的素数进行乘法，我们确保每个组合仅构造一次。 DFS 精确地探索限制下有效数字的空间，而二分搜索则利用阈值和可达数字计数之间的单调关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1000000)

primes = []

def count_leq(x):
    n = len(primes)
    res = 0

    def dfs(i, val):
        nonlocal res
        res += 1
        for j in range(i, n):
            p = primes[j]
            if val > x // p:
                break
            dfs(j, val * p)

    dfs(0, 1)
    return res

def solve():
    global primes
    n = int(input())
    primes = list(map(int, input().split()))
    k = int(input())

    lo, hi = 1, 10**18

    while lo < hi:
        mid = (lo + hi) // 2
        if count_leq(mid) >= k:
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```DFS 的结构经过精心设计，因此每次递归调用都表示将有效因式分解再扩展一个质因数。 分工检查`val > x // p`避免溢出并在值增长超出限制时保持积极修剪。 二分查找封装了这个计数函数来定位第 k 个数字出现的确切阈值。 

一个常见的错误是允许 DFS 在每个级别从索引 0 重新启动，这会导致相同因式分解的排列。 约束条件`for j in range(i, n)`是强制规范排序的原因。 

## 工作示例

 考虑带有素数的样本`[2, 3, 5]`k = 7。 

DFS 枚举结构深度不断增加的数字，但从概念上讲，有效序列是：

 | 步骤| 当前 x | 新扩展|
 | ---| ---| ---|
 | 1 | 1 | 2、3、5 |
 | 2 | 2 | 4、6、10 |
 | 3 | 3 | 6、9、15 |
 | 4 | 4 | 8、12、20 |

 通过构造规则去重后，排序顺序变为：

 1, 2, 3, 4, 5, 6, 8, ...

 第 7 个元素是 8，与输出匹配。 

现在考虑一个带有素数的较小的自定义示例`[2, 3]`k = 5。 

| 步骤| 提取订单|
 | ---| ---|
 | 1 | 1 |
 | 2 | 2 |
 | 3 | 3 |
 | 4 | 4 |
 | 5 | 6 |

 结果是 6。 

该跟踪显示了由于 DFS 中索引递增的约束，产品如何分支但仍保持有序和唯一。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(log(10^18)·S) | O(log(10^18)·S) | 对值范围进行二分搜索，每一步对限制内的所有有效产品运行 DFS |
 | 空间| O(n) | 递归深度受素数数量和乘积链增长的限制 |

 可达状态的数量由乘积的快速增长控制，因为每次乘以素数 ≥ 2 都会很快超出界限，从而保持 DFS 的可管理性。 结合固定 64 位范围内的二分搜索，该解决方案完全符合限制。

 ## 边缘情况

 当 n = 1 时，序列变为单个素数加 1 的幂。任何从素数本身而不是 1 开始枚举的解决方案都会移动所有索引并返回错误结果。 

当 k = 1 时，无论素数如何，答案始终为 1。 如果实现假设第一个生成的值必须来自素数相乘一次，则经常会忽略这一点。 

当 k 很大但值增长很快时，即使答案的大小很小，通过索引进行的简单生成也会超时。 这正是需要对值空间进行二分搜索而不是序列构造的情况。
