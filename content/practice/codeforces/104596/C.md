 ## 解决方案
 ## 问题理解

 我们有几种类型的原材料，特别是不同的奶酪，每种奶酪的数量有限，以磅为单位。 除此之外，还有几种可能的最终产品，即奶酪混合物。 每种混合奶酪都有固定的配方：每磅混合奶酪必须使用固定百分比的每种奶酪类型。 每种混合物在出售时每磅也有固定的利润。 

我们的任务是决定每种奶酪的生产量，这样我们就不会超出任何奶酪类型的可用供应量，同时使总利润最大化。 我们生产的每个单位的混合物都会根据其配方消耗多种奶酪类型的分数，因此这不是一个简单的分配问题，而是一个连续分配问题，其中混合物可以少量生产。 

限制很小：奶酪类型和混合物的数量最多为 50 种。这立即表明需要采用多项式时间优化方法，而不是对混合物数量进行暴力破解。 然而，关键的困难在于生产是连续的并且受到多个共享资源的限制，这创建了可行解决方案的几何结构而不是组合搜索空间。 

一个天真的想法是尝试每种混合的所有可能的生产水平，但即使是小步离散也会很快爆炸，因为原则上每个混合数量都是连续的。 另一种幼稚的尝试是贪图每磅的利润，但这会失败，因为不同的混合奶酪会争夺具有不同成分的共享奶酪。 

当高利润的混合物大量消耗稀缺的奶酪而低利润的混合物仅使用丰富的奶酪时，就会出现微妙的边缘情况。 贪婪策略会选择高利润的混合物，耗尽瓶颈资源并阻止产生更多总利润的低利润混合物的组合。 当两种混合具有相同的利润但不同的资源配置时，会出现另一种边缘情况，其中最优解决方案完全取决于约束的全局交互而不是局部偏好。 

该结构强烈暗示了线性规划公式：我们在线性约束下最大化线性目标。 

## 方法

 直接的暴力方法会将每种混合物视为代表我们生产了多少磅的变量。 如果我们以小增量离散化生产，我们就可以枚举生产水平的所有组合。 即使采用 1 磅这样的粗步长，状态空间也会变得巨大，因为最多 50 个混合中的每一个都可以独立地达到数百个单位。 这导致大约$500^{50}$最坏的情况下的可能性，这是完全不可行的。 

关键的观察结果是约束和目标都是线性的。 每种奶酪类型都会在混合变量上产生线性不等式，而利润是这些变量的线性函数。 这正是线性规划问题的结构。 

我们可以依靠这样一个事实：线性规划的最优解出现在可行区域的极值点，而不是搜索离散选择。 这使我们能够应用单纯形法或任何标准 LP 求解器。 考虑到变量和约束的维数较小（均以 50 为界），仔细实现的单纯形算法就足够了，并且在此类问题的竞争性编程设置中是标准的。 

我们将每种混合建模为变量$x_j$，代表生产的磅数。 对于每种奶酪类型$i$，我们施加一个限制，即所有混合物的总使用量不超过可用供应量。 每次混合消耗$p_{ij} / 100$磅奶酪$i$每生产一磅。 目标是最大化总和$t_j x_j$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 以 m 为单位的指数 | O(百万) | 太慢了|
 | 线性规划（单纯形）| 最坏情况呈指数增长，实践中速度很快 | O(纳米) | 已接受 |

 ## 算法演练

 我们将问题作为线性程序来解决，其中变量代表我们生产的每种混合物的数量。 

1. 将每个混合转换为变量$x_j$，代表该混合物的磅数。 这种重新表述将问题转化为对连续变量而不是组合决策的优化。 
2. 对于每种奶酪类型$i$，构建一个约束，确保我们不会超出可用库存。 总用量为$\sum_j (p_{ij}/100) x_j \le w_i$。 这直接增强了消费的物理可行性。 
3. 将目标函数定义为最大化$\sum_j t_j x_j$，因为利润与产量成线性关系。 
4. 将所有约束转换为适合单纯形的标准线性规划形式，引入不等式的松弛变量。 这会将可行区域转换为多面体。 
5. 从原点可行解开始运行单纯形算法。 在每次迭代中，我们沿着多胞体的边缘移动以改善目标。 
6. 当不存在改进的枢轴时终止。 当前解对应于可行区域的一个顶点，保证对于线性规划来说是最优的。 

为什么它有效：由线性不等式定义的可行区域是凸多面体，并且目标在该区域上是线性的。 任何局部改进方向都沿着边缘，并且最优性必须发生在顶点处。 单纯形法系统地遍历目标值不断增加的顶点，并且由于顶点数量有限，因此它最终会达到最优状态，而无需重新访问更好的状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

EPS = 1e-9

def simplex(A, b, c):
    # maximize c^T x subject to A x <= b, x >= 0
    n = len(c)
    m = len(b)

    # tableau: m constraints + objective
    N = n + m
    M = m + 1

    tab = [[0.0] * (N + 1) for _ in range(M)]

    # constraints
    for i in range(m):
        for j in range(n):
            tab[i][j] = A[i][j]
        tab[i][n + i] = 1.0
        tab[i][-1] = b[i]

    # objective row
    for j in range(n):
        tab[m][j] = -c[j]

    def pivot(r, c_):
        inv = tab[r][c_]
        tab[r] = [v / inv for v in tab[r]]
        for i in range(M):
            if i != r:
                factor = tab[i][c_]
                if abs(factor) > EPS:
                    tab[i] = [tab[i][k] - factor * tab[r][k] for k in range(N + 1)]

    while True:
        col = -1
        for j in range(N):
            if tab[m][j] < -EPS:
                col = j
                break
        if col == -1:
            break

        row = -1
        best = 0
        for i in range(m):
            if tab[i][col] > EPS:
                val = tab[i][-1] / tab[i][col]
                if row == -1 or val < best:
                    best = val
                    row = i

        if row == -1:
            break

        pivot(row, col)

    return tab[m][-1]

矩阵 A[i][j] 是每磅混合物 j 使用的奶酪 i 的量，即 pi / 100。矢量 b 可由 wi 提供。 目标 c 是每磅利润。 

单纯形实现维护一个表，其中松弛变量代表未使用的奶酪。 旋转将非基本变量（混合量）交换为基础，同时保持可行性。 该算法重复选择具有负降低成本的变量并执行最小比率测试以保持可行性。 

必须小心浮点比较，因为百分比值和利润引入了小数算术。 EPS 用于避免枢轴选择的不稳定。

 ## 边缘情况

 一个关键的边缘情况是当一种奶酪类型从未被任何混合物使用时。 在这种情况下，相应的约束是多余的并且不应该影响可行性。 单纯形公式自然可以处理这个问题，因为行保持松弛并且永远不会变得有约束力。 

当多种混合具有相同的利润但不同的消费向量时，会出现另一种边缘情况。 该算法可以在它们之间转动而不改变目标值。 这是安全的，因为所有这些顶点都是最优的并且代表等效的解决方案。 

最后一个微妙的情况是当 0.1 或 0.3 等百分比跨约束累积时浮点不稳定。 EPS 阈值确保忽略接近零的主元元素，从而防止不正确的基础交换，否则会违反可行性。
