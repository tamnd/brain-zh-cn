 ## 解决方案
 ## 问题理解

 我们有一张矩形纸板，其尺寸为$a \times b$。 我们从每张纸的四个角切出相等的正方形并将侧面折叠起来，形成一个开顶盒子。 切割尺寸为整数$x$，它确定了一个带有底座的盒子$(a - 2x) \times (b - 2x)$和身高$x$。 每个有效$x$生成一个盒子，该盒子可以容纳等于其体积的单位立方书籍的数量：$$V(x) = x \cdot (a - 2x) \cdot (b - 2x).$$在所有有效的整数切割尺寸中，仅考虑三个最大的盒子容量。 对于这三种盒子类型中的每一种，我们尝试包装固定的未知数量的书籍$N$。 当以给定的盒子容量进行包装时$V$，我们填充尽可能多的满框，剩下的余数等于$N \bmod V$。 这些余数分别针对最大、第二大和第三大盒子容量给出。 

此外，图书总数位于已知区间内$[f, g]$，并且保证解是唯一的。 

任务是重建$N$。 

对于几何形状的约束很小（$a, b \le 100$），因此可能的框大小最多约为 50 个。这立即表明枚举所有候选框配置是可行的。 困难的部分不是几何，而是在大数值范围内一致地对齐多个模块化约束，直到$10^9$。 

天真的方法会尝试每一个$N$在$[f, g]$并检查所有余数条件是否成立。 这将需要最多$10^9$在最坏的情况下进行检查，这是不可能的。 

第二个幼稚的错误是独立地对待三个同余，而不考虑它们对于相同的未知数必须同时成立$N$。 每个盒子大小定义了不同的模数，因此解决方案必须位于三个模算术约束的交集处，而不是三个单独的检查。 

当多种切割尺寸产生相同的体积时，会出现微妙的边缘情况。 在这种情况下，“前三个盒子尺寸”必须指按体积计算的三个最佳不同配置，而不仅仅是不同的配置$x$盲目地按递增顺序取值。 

## 方法

 一旦确定了正确的解释，几何部分就很简单了。 对于每个整数$x$这样$1 \le x < \min(a, b)/2$，我们可以计算体积$V(x)$。 这给出了一小部分候选能力。 按体积对这些进行排序，得出最大、第二大和第三大可用盒子容量。 

然后，针对整个问题的强力策略将迭代所有整数$N$在$[f, g]$，并且对于每个$N$检查是否：$$N \bmod V_1 = c,\quad N \bmod V_2 = d,\quad N \bmod V_3 = e.$$这是正确的，但太慢了，因为间隔可以跨越$10^9$。 

关键的观察是每个条件都限制$N$残基类别以其相应体积为模。 我们可以逐步交叉这些模块化约束，而不是扫描所有数字。 我们首先修复一个同余，然后过滤满足第二个同余的候选，最后是第三个同余。 因为模量很小（最多大约$100^3$），单步执行算术级数是高效的。 

一种更结构化的方式来看待这个问题是，我们正在解决一个具有非互质模的同余系统，但我们通过在给定范围内使用增量过滤来避免完整的中国剩余定理机制。

 | 蛮力结束$N \in [f,g]$|$O(g-f)$|$O(1)$| 太慢了|
 | 小候选模上的模交 |$O(\min(g-f, V_1))$|$O(1)$| 已接受 |

 ## 算法演练

 ## 算法演练

 1. 枚举所有有效的切割尺寸$x$从 1 到$\min(a, b)/2 - 1$，并计算$V(x) = x(a-2x)(b-2x)$。 

这是有效的，因为任何有效的盒子都必须来自整数切割尺寸，并且该公式完全确定其容量。 
2.全部排序$(V(x), x)$按数量降序排列的对。 

我们按数量跟踪最好的三种不同配置。 
3.提取前三卷$V_1, V_2, V_3$，以及它们相应的余数$c, d, e$。 

这些定义了三个模块化约束：$$N \equiv c \pmod{V_1}, \quad
N \equiv d \pmod{V_2}, \quad
N \equiv e \pmod{V_3}.$$4. 生成所有数字$N$在$[f, g]$通过写满足第一个同余：$$N = c + kV_1.$$从最小的这样开始$N \ge f$，然后逐步$V_1$。 
5. 对于每位候选人$N$，检查是否也满足：$$N \bmod V_2 = d \quad \text{and} \quad N \bmod V_3 = e.$$第一场比赛是唯一的答案。 

### 为什么它有效

 每个盒子大小定义了未知书籍总数的固定模块化条件。 真实数字$N$必须位于三个算术级数的交集中，所有算术级数都进一步限制在有限区间内。 通过生成一个模数的完整级数并过滤其他模数，我们确保不会遗漏任何有效的解决方案，因为每个解决方案都必须出现在第一个级数中并通过两次检查。 唯一性保证第一个幸存的候选者就是答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b, c, d, e, f, g = map(int, input().split())

    vals = []

    limit = min(a, b) // 2
    for x in range(1, limit):
        v = x * (a - 2 * x) * (b - 2 * x)
        if v > 0:
            vals.append((v, x))

    vals.sort(reverse=True)

    # take top 3 volumes
    top = vals[:3]
    V1, V2, V3 = top[0][0], top[1][0], top[2][0]
    c1, c2, c3 = c, d, e

    # ensure correct association already given by order
    def check(n):
        return (n % V1 == c1 and n % V2 == c2 and n % V3 == c3)

    start = f
    r = (start - c1) % V1
    n = start + (V1 - r) % V1

    while n <= g:
        if check(n):
            print(n)
            return
        n += V1

solve()
```枚举切割尺寸是安全的，因为$a, b \le 100$，因此最多测试 50 个候选值。 排序可以忽略不计。 

搜索阶段通过在与第一个模数一致的数字之间直接跳转来避免在整个范围内迭代。 对齐步骤确保第一个候选者在$[f, g]$，防止低于间隔的浪费迭代。 

一个常见的实施陷阱是忘记正确调整起点； 直接开始于$c$可以将搜索置于所需范围之外或之前$f$。

 ## 边缘情况

 当多种切割尺寸产生非常接近或相同的体积时，就会出现关键的边缘情况。 在这种情况下，选择前三名必须严格按照数量排名来进行，而不是选择最大的$x$价值观。 

例如，如果两种不同的切割尺寸产生相同的容量，则排序步骤仍必须将它们视为不同的候选者，但必须注意“前三名”指的是具有最高容量的三种配置，而不仅仅是三个最大的配置$x$。 

另一个边缘情况是当算术级数中的第一个有效候选者正好位于下面时$f$。 如果我们开始从$c$直接地，我们可能会浪费很多迭代或者错过与范围的对齐。 正确的初始化确保第一个检查的值是至少是级数中的最小数字$f$。
