 ## 解决方案
 ## 问题理解

 我们得到了一系列书籍，在阅读下一本书之前，必须从头到尾阅读每本书。 每本书都有页数长度和以天为单位的截止日期。 读者对所有书籍都使用单一恒定的阅读速度，以​​每天的页数来衡量，完成一本书所需的天数等于其长度的上限除以速度。 由于书籍是按顺序处理的，因此每本书的完成日期是这些持续时间的累积总和。 

如果一本书完成的日期超过了截止日期，则被视为迟到。 任务是选择尽可能小的整数阅读速度，使得最多 m 本书迟到。 

限制允许最多 100,000 本书，长度最多为 10^9，截止日期最多为 10^4。 这立即排除了任何天真的尝试所有速度并完全模拟每个速度的方法。 即使单个完整模拟也是 O(n)，因此尝试高达 10^9 的所有速度是不可能的。 有效的解决方案必须显着减少候选速度的数量，并且仍然有效地评估每个候选。 

一个微妙的问题来自如何定义迟到。 迟到与每本书无关； 这取决于累计阅读时间。 一个幼稚的错误是单独比较每本书，而忽略了早期的长书会延迟所有后续的书。 

另一个常见的陷阱是天花板划分处理不当。 如果整数除法直接用作 l // s，则只要 l 不能被 s 整除，它就会低估时间，这可能会错误地减少累积调度并产生看似可行的无效速度。 

## 方法

 一个简单的尝试是尝试从 1 到最大书籍长度的所有可能的阅读速度。 对于每种速度，我们模拟按顺序阅读所有书籍，计算每本书的完成日期，计算有多少本书超出了截止日期，并检查这个数字是否最多为 m。 这是正确的，因为它直接反映了问题中描述的过程。 然而，成本却令人望而却步。 如果我们测试 S 个可能的速度，每个速度都需要 O(n) 模拟，则总成本为 O(Sn)，在最坏的情况下约为 10^14 次操作。 

关键的结构观察是，提高阅读速度只会有所帮助。 如果某个速度 s 足以让最多 m 本书迟到，那么任何更大的速度都将不晚于速度 s 完成每本书，因此不能增加迟到书的数量。 这种单调行为使我们能够将问题视为对排序谓词的搜索：可行的速度形成所有整数的后缀。 

一旦我们认识到单调性，我们就可以对答案应用二分搜索。 对于候选速度，我们模拟一次来计算有多少本书迟到了。 这将模拟数量从答案范围内的线性减少为对数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解所有速度 | O(最大L·n) | O(1) | O(1) | 太慢了|
 | 二分查找+模拟| O(n log maxL) | O(n log maxL) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们利用了可以独立测试速度可行性的事实。

1. 定义一个函数来检查给定速度是否有效。 我们模拟按顺序阅读所有书籍，并保持所花费的总天数。 对于每本书，我们添加完成它所需的天数，计算公式为 (l + s − 1) // s。 更新累计时间后，我们检查完成日期是否超过该书的截止日期。 如果是这样，我们就把它算作迟到的书。 
2. 如果迟到书的数量最多为 m，则 check 函数返回 true。 这给了我们一个关于速度的单调谓词。 
3. 我们为答案设置一个二分搜索范围。 可能的最小速度是 1。所需的最大速度是最大的书本长度，因为以该速度一天内可以读完任何一本书。 
4. 我们在这个范围内执行二分查找。 对于每个中点速度，我们都会进行可行性检查。 
5. 如果速度可行，我们尝试通过向下移动右边界来降低速度。 如果不可行，我们可以通过向上移动左边界来提高速度。 
6、二分查找收敛后，左边界为最小可行速度。 

为什么有效：模拟定义了一个关于单调非递增速度的谓词。 一旦速度足以将迟到控制在允许的范围内，所有较大的速度都会保留或提高每个完成时间，因此它们无法增加迟到书籍的数量。 这就保证了可行区域是连续的，这正是二分查找找到最小有效速度所需的条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def check(speed, books, m):
    time = 0
    late = 0
    for l, d in books:
        time += (l + speed - 1) // speed
        if time > d:
            late += 1
            if late > m:
                return False
    return True

def solve():
    n, m = map(int, input().split())
    books = [tuple(map(int, input().split())) for _ in range(n)]

    lo, hi = 1, max(l for l, _ in books)

    while lo < hi:
        mid = (lo + hi) // 2
        if check(mid, books, m):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```仿真是解决方案的核心。 变量`time`表示当前书籍完成的累计日期，而不是每本书的持续时间。 这种积累至关重要，因为每本书只有在前一本书完成后才开始。 

吊顶划分`(l + speed - 1) // speed`确保正确计算部分天数。 如果没有这种调整，长度不能被速度整除的书籍将错误地显示得比实际速度快，这会破坏正确性。 

二分查找保持以下任何速度的不变性`lo`无效，而任何速度等于或高于`hi`是有效的。 检查功能一致地强制执行可行性条件，从而使搜索能够安全地收敛。 

## 工作示例

 考虑示例输入：

 n = 3，m = 1

 书籍：(450, 9)、(500, 6)、(300, 4)

 我们使用二分搜索来测试候选速度。 

| 速度| 第 1 册完成 | 第 2 册完成 | 第 3 册完成 | 迟到计数 | 可行|
 | ---| ---| ---| ---| ---| ---|
 | 1 | 450 | 450 950 | 950 1250 | 1250 3 | 没有|
 | 2 | 225 | 225 475 | 475 625 | 625 2 | 没有|
 | 3 | 150 | 150 317 | 317 417 | 417 1 | 是的 |

 对于 Speed 2，第二本书在第 475 天完成，已经超过了最后期限 6，而第三本书也错过了。 这产生了太多迟到的书。 在速度 3 时，只有一本书迟到，满足约束条件，因此答案为 3。 

此跟踪显示迟到如何取决于累积完成时间，而不是单个书籍的持续时间。 即使速度适度增加也会显着推迟完成时间。

 ## 边缘情况

 一个关键的边缘情况是只允许一本书迟到。 在这种情况下，最佳速度通常恰好高于一本长书不再违反最后期限的阈值。 二分搜索正确地捕获了这一点，因为可行性函数从假到真恰好翻转一次。 

另一个重要的情况是，所有截止日期与书籍长度相比都非常短。 例如，如果每个截止日期都为1，则只有等于最大书籍长度的速度才能确保任何一本书都可以在一天内完成； 否则所有的书很快就会迟到。 该算法自然地处理了这个问题，因为可行性检查根据累积时间来计算延迟，而二分搜索将直接推动所需的最大速度。 

最后，当 m 很大，接近 n − 1 时，几乎任何速度都可以接受。 检查功能仍然通过计算多余的迟交书籍来强制正确性，并且二分搜索将收敛到避免时间表中单个最坏故障点的最小速度。
