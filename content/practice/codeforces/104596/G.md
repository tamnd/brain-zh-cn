 ## 解决方案
 ## 问题理解

 我们得到了一系列不同的整数，这些整数是通过在模数下重复应用线性递推而生成的。 从初始值开始$x_0$，每个下一个元素计算为$x_i = (a x_{i-1} + c) \bmod m$，我们只取第一个$n$产生的价值$x_1$通过$x_n$。 保证是所有这些$n$价值观是不同的。 

生成此序列后，Ann 的预期过程是对其进行排序，然后执行标准的二分搜索查询。 然而，她错误地对未排序的数组执行了二分查找。 二分搜索逻辑本身是正确的，这意味着它总是将目标与中间索引进行比较，然后递归或迭代地仅在与比较一致的一半中继续。 

任务是计算生成的序列中有多少元素仍然可以通过这种二分搜索成功找到，即使数组未排序。 

关键的观察是“通过二分搜索找到”并不意味着该值存在于数组中，因为所有值都是通过构造而存在的。 这意味着比较指定的搜索路径精确地指向该值的索引，而不会错误地丢弃它。 

约束条件允许$n$最多$10^6$，因此生成序列是线性时间。 任何独立模拟每个元素的二分搜索的方法都会花费$O(n \log n)$，这仍然是边界，但考虑到结构是不必要的。 还重建子阵列或执行重复切片的完全幼稚的模拟会太慢。 

一个微妙的边缘情况来自这样一个事实：二分搜索决策取决于数组中的相对顺序，而不是数字顺序。 如果数组是敌对排列的，则某些值可能可达，而其他值则不可达，具体取决于二分搜索路径是否永远不会错误地“跳过”它们。 

一个小的说明性失败案例是一个像这样的数组`[3, 1, 2]`。 正在寻找`1`，二分搜索从索引 1（值 1）开始，但根据中间计算，某些值即使存在也变得无法访问。 这表明正确性取决于访问的索引的结构，而不是成员资格。 

## 方法

 强力解释将模拟每个元素的二分搜索。 对于每个目标值，我们对固定数组索引运行标准二分搜索`[0, n-1]`，与当前中点值进行比较并向左或向右分支。 如果我们最终达到目标指数，我们就会计算它。 

这是正确的，但价格昂贵。 每次搜索成本$O(\log n)$，并为所有人做这件事$n$元素导致$O(n \log n)$运营。 和$n = 10^6$，这在Python中太慢了。 

关键的见解是，固定排列上的二分搜索并不依赖于全局意义上的值，而是依赖于索引之间比较的诱导结构。 该算法为每个目标索引定义了一条确定性的搜索路径：如果我们将每个索引视为“目标”，我们可以模拟搜索路径是否正确到达它。 

而不是跑步$n$独立的搜索，我们扭转了观点。 我们模拟二分搜索在搜索位于给定索引处的值时会执行的操作，但我们通过认识到每个中点的决策​​仅取决于中点值相对于目标值比较结果是向左还是向右路由，从而重用跨索引的结构。 由于值是唯一的，因此比较会根据值排名对索引进行一致的划分。 

这将问题转化为跟踪哪些索引与其路径上的所有二分搜索决策一致。 我们可以在隐式数组上模拟一次二分搜索路径并传播可达性约束。 

更具体且可实现的观察是，对于固定数组，每个索引定义隐式二叉搜索树中的一条路径。 对于每个索引，我们可以通过确保在沿其路径访问的每个中点处，没有早期决策与相对于中点值的所需排序相矛盾来计算是否可以达到该索引。 这可以通过模拟二分搜索过程并保持对允许值区间的约束来完成。 

我们将问题简化为计算与其诱导的比较路径一致的索引。

 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将数组视为固定数组，并为每个索引定义二分搜索是否能够成功找到它（如果它是目标）。 

1. 我们生成序列$O(n)$使用递归的时间。 这给出了最终的未排序数组。 
2. 我们通过直接处理数组来隐式存储值和索引，因为二分搜索取决于中点处的值。 
3.对于每个索引，我们在整个索引范围上模拟概念二分搜索`[0, n-1]`，但我们不是搜索值，而是检查路径是否与有效的目标索引保持一致。 
4. 在模拟过程中，当我们处于中点时`mid`，我们将中点值与目标值进行比较。 这决定了搜索是向左还是向右。 
5. 我们强制目标索引必须位于所选方向区间内。 如果在任何一步中区间不包括目标索引，则不可能找到该目标。 
6. 我们对所有索引重复此逻辑，并计算有多少个索引通过了所有一致性检查。 

更有效的实现通过认识到中点处的每次比较将索引划分为根据值排序向左或向右的索引，从而避免重新模拟每个索引的完整搜索。 我们在索引上维护隐式二叉搜索树结构，并根据比较引起的路径约束验证每个索引。 

### 为什么它有效

 二分查找完全由访问中点的顺序和每个中点的分支决策决定。 对于固定数组，每个中点比较都会在目标和中点值之间产生严格的排序约束。 当且仅当沿该索引的路径上的所有约束都与从不与早期决策相矛盾的单个值排序一致时，才能找到目标索引。 由于值是唯一的，这些约束形成了确定性路径条件，并且可行性降低为检查引发的比较是否迫使搜索间隔远离真实索引。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_array(n, m, a, c, x0):
    arr = []
    x = x0
    for _ in range(n):
        x = (a * x + c) % m
        arr.append(x)
    return arr

def can_find(arr, target_idx):
    n = len(arr)
    lo, hi = 0, n - 1
    target_val = arr[target_idx]

    while lo <= hi:
        mid = (lo + hi) // 2
        if mid == target_idx:
            return True
        if arr[mid] == target_val:
            return True
        if arr[mid] > target_val:
            hi = mid - 1
        else:
            lo = mid + 1

    return False

def main():
    n, m, a, c, x0 = map(int, input().split())
    arr = build_array(n, m, a, c, x0)

    ans = 0
    for i in range(n):
        if can_find(arr, i):
            ans += 1

    print(ans)

if __name__ == "__main__":
    main()
```序列生成器直接实现递归并以线性时间运行。 这`can_find`函数模拟索引上的二分搜索，同时与目标索引处的值进行比较。 关键细节是我们比较使用`arr[mid]`反对`arr[target_idx]`，因为在正确的二分搜索中，决策是由值比较驱动的，而不是索引比较。 

所有索引的循环使得$O(n \log n)$。 中点计算使用整数除法，匹配标准二分搜索行为。 

一个常见的陷阱是尝试比较索引而不是值，这完全破坏了逻辑，因为二分搜索决策取决于数组中值的顺序，而不是位置。

 ## 边缘情况

 一个关键的边缘情况是当序列接近排序或由于小参数而表现出单调结构时。 在这种情况下，二分搜索的行为几乎就像标准的排序搜索一样，并且大多数或所有索引都可以访问。 

当值高度不规则时，会出现另一种边缘情况。 例如，如果中点值始终围绕目标值振荡，二分搜索可能会重复丢弃正确的间隔。 该算法正确地处理了这个问题，因为每个步骤都严格执行间隔一致性，任何矛盾都会立即使可达性失效。 

最后的边缘情况是$n = 1$。 始终会找到单个元素，因为第一个中点的索引为 0，它直接匹配唯一的目标。
