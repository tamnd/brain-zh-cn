 ## 解决方案
 ## 问题理解

 我们正在跟踪 Maxim 通过一系列问题解决的日常问题$n$天。 他每天至少解决一个问题，我们希望为每一天分配一个精确的正整数。 

每天观察到两个量$i$。 第一个是最近解决的问题总数$k$天数结束于$i$，其行为类似于滑动窗口的长度总和$k$。 第二个是结束于的连续天数$i$期间他每天都在解决问题，这就是目前的连胜长度。 

规则是每天的滑动窗口总和是过去一天的总和$k$天数必须至少与当前的连续长度一样大。 我们被告知这个条件已经适用于所有人$n$天，我们必须重建满足约束的每日值序列，同时最小化所有值的总和$n$天。 

输入给出$k$，窗口大小，以及$n$，天数。 输出是解决的问题的最小可能总数。 

约束条件达到$10^6$，因此任何解都必须是线性或近线性的$n$。 所有有效序列的二次重建或滑动窗口的重复重新计算是不可能的，因为即使$O(nk)$将达到$10^{12}$最坏情况下的操作。 

一个天真的想法是尝试每天分配尽可能小的值（通常为 1），并检查是否违反约束。 当滑动窗口与条纹增长相比太小时，就会出现失败情况。 例如，当$k = 2$，第三天的窗口仅与前两天部分重叠，因此简单地将所有值保留为 1 很快就不足以满足涉及增长趋势的不等式。 幼稚的模拟会反复调整早期的值，导致级联更新，使其速度太慢。 

另一个微妙的问题是，约束取决于移动总和和全局连续，因此局部贪婪的选择可能会在稍后不立即检测到的情况下破坏可行性。 

## 方法

 暴力方法将逐日进行模拟，维护完整的数组，并每天重新计算条纹长度和过去的总和$k$天。 如果当天违反约束$i$，我们会尝试增加一些先前的值来修复它。 在最坏的情况下，每次调整都可能向后传播$k$位置，并且这种情况可能会重复很多天。 这会导致最坏情况的复杂性约为$O(nk)$，因为每天可能都需要重新计算和修复滑动窗口。 

关键的观察是约束仅取决于两个单调量：条纹确定性地增长（它总是$i$），并且滑动窗口总和由大小有限的窗口控制$k$。 这种不平等迫使窗口总和“跟上”线性增长，但只能通过局部调整。 这表明我们永远不需要重新审视决策$k$退一步，因为任何比$k$天数不再影响约束。 

这导致了贪婪的构造：维护当前的窗口总和并确保当连续增加时，我们最小限度地增加窗口中的一些值以恢复可行性。 最佳结构最终是周期性的：每天我们都确保最后有足够的质量$k$一旦系统稳定，就会产生重复的模式。

 | --- | --- | --- | --- |
 | 蛮力 |$O(nk)$|$O(n)$| 太慢了|
 | 最佳|$O(n)$|$O(k)$| 已接受 |

 ## 算法演练

 我们增量地构建序列，同时保持最后一个的滑动窗口和$k$值并确保它始终至少为当前条纹长度。 

1.初始化一个数组或者滚动结构来存储最后的$k$值，全部从 1 开始。这是最小的可能选择，因为每天至少会产生一个问题。 
2. 维护最后的运行总和$k$天。 最初，对于第 1 天，总和为 1，条纹为 1，因此约束成立。 
3. 从第一天到第二天迭代$n$。 对于每一天$i$，计算当前的连续值，即$i$，因为序列是连续的。 
4. 计算最后一个的当前窗口总和$k$元素。 如果$i \le k$，窗口是前缀和$i$; 否则就是总和$i-k+1$到$i$。 
5. 如果窗口总和已经至少为$i$，我们为当天分配最小值 1，更新窗口，然后继续。 
6. 如果窗口总和小于$i$，我们必须增加当天的值，以使窗口总和恰好变为$i$。 这是最优的，因为增加早期值只会增加总和，而不会减少未来的需求。 
7. 分配日期值后$i$，通过添加新值并删除掉出窗口的值来更新滑动窗口，如果$i > k$。 

关键的结构思想是，约束中的每一个赤字都可以在当前贪婪地修复，并且永远不需要重新分配到过去。 

### 为什么它有效

 任何一天$i$，约束仅取决于最后的总和$k$元素和值$i$。 不等式中的任何赤字都意味着当前窗口总和太小而无法满足所需的阈值。 由于窗口外的所有早期日期不再影响约束，因此修复可行性的唯一方法是增加当前窗口内的值。 

增加窗口内的早期头寸或当前头寸在可行性方面是等效的，但增加当天的头寸是最佳的，因为它不会冒违反前几天限制的风险，这些限制已经得到满足。 这创建了一个局部最优的修复步骤，该步骤永远不会使过去的正确性失效，从而建立一个稳定的贪婪不变量：处理日后$i$，所有约束条件达到$i$保持，并且窗口总和始终是最小足够的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    k, n = map(int, input().split())
    
    from collections import deque
    window = deque()
    window_sum = 0
    
    total = 0
    
    for i in range(1, n + 1):
        # remove element leaving window
        if len(window) == k:
            window_sum -= window.popleft()
        
        # current streak requirement
        need = i
        
        # minimum value is 1
        val = 1
        
        # check window constraint
        if window_sum + val < need:
            val = need - window_sum
        
        window.append(val)
        window_sum += val
        total += val
    
    print(total)

if __name__ == "__main__":
    solve()
```该实现维护一个代表最后一个的双端队列$k$值和运行总和来支持$O(1)$更新。 每天，我们确保至少分配 1 个问题。 如果这不足以使滑动窗口总和满足当前的连续要求，我们会增加当天的值以满足相等性。 

关键细节是窗口在评估约束之前更新，因此总和始终准确反映最后一个$k$天。 这避免了滑动范围中的相差一误差。

 ## 边缘情况

 一个关键的边缘情况是$k = 1$。 该窗口仅包含当前日期，因此约束变为当天的值$i$必须至少是$i$。 该算法准确地分配$i$，产生三角形生长序列$1,2,3,\dots,n$。 滑动窗口始终完全符合要求，因此无需额外调整。 

另一个边缘情况是当$k \ge n$。 窗口永远不会丢弃旧值，因此总和始终是累积的。 在这种情况下，为每天分配 1 是最佳选择，因为一天之后的窗口总和$i$正是$i$，它总是与所需的条纹相匹配。 

更微妙的情况发生在$k$很小，比如$k = 2$。 早期的行为就像$k \ge n$但一旦窗口变满，旧的小值将被丢弃。 这是算法开始注入较大值的地方，如示例 1 所示。当天的贪婪修正确保了可行性，而无需重新访问早期的分配。
