 ## 解决方案
 ## 问题理解

 我们正在使用帕斯卡三角形，其中每一行都是通过添加相邻对来从前一行构建的，并且边始终为 1。每一行都从零开始索引，并且在一行内，位置也从零开始索引。 

与通常的构建问题相比，该任务是相反的。 我们没有构建三角形，而是得到了一个数字`n`并询问它是否出现在无限帕斯卡三角形中的任何位置。 如果确实出现，我们必须返回任何有效的对`(row, position)`该值出现的位置。 如果它从未出现，我们输出`-1`。 

关键的困难在于三角形的宽度和值增长得非常快，但是输入`n`比较小，最多只有一百万。 这立即表明我们不能处理三角形下方的任意组合值，因为二项式系数的增长速度非常快，远远超出了这个范围。 因此，任何有效的解决方案都必须依赖于小行结构或早期重复模式，而不是深度枚举。 

一个天真的解释是生成行，直到值超过`n`，但这隐藏了一个微妙的陷阱：帕斯卡的三角形值的大小迅速增加，但小值仅在特定位置重新出现，而一些值如`1`或者`2`出现在很多行中。 如果粗心的生成器只跟踪行的前缀，它可能会过早停止或错过有效的出现。 

对于较小的值，边缘情况会立即出现。 为了`n = 1`，它存在于`(0,0)`以及每行边界上。 为了`n = 2`，它出现在`(2,1)`和`(2,0)`对称性方面，但后来也出现在较大的行中，例如`(3,1)`或者`(3,2)`？ 实际上在帕斯卡三角形中，`2`仅出现在第 2 行及之后的特定二项式系数处，因此任何关于每行值唯一的错误假设都会导致错误的修剪。 另一个边缘情况是`n = 0`，它不是输入域的一部分，但提醒我们只有正项才重要。 

最重要的隐藏约束是帕斯卡三角形中的值是二项式系数，并且对于`n ≤ 10^6`，只有非常小的行可以包含此类值。 这种观察使问题变得容易处理。 

## 方法

 蛮力的想法很简单：逐行生成帕斯卡三角形，使用递归计算每个值`C(r, c) = C(r-1, c-1) + C(r-1, c)`，并检查是否有任何值等于`n`。 这是正确的，因为它直接模拟了定义。 然而，它的计算成本很高。 排`r`包含`r+1`元素，因此生成最多行`R`费用约为`O(R^2)`运营。 即使对于中等`R = 2000`，这已经是几百万的添加，如果我们不幸并且需要​​更深的行，那么与我们实际需要的相比，成本就变得不必要了，因为`n ≤ 10^6`强烈限制有意义的搜索深度。 

关键的观察结果是二项式系数增长得非常快。 中心二项式系数`C(r, r/2)`大约是`2^r / sqrt(r)`。 这超过了`10^6`大约`r ≈ 20`。 这意味着在所有值变得大于之前，我们只需要搜索非常少量的行（大约几十行）`n`。 因此，我们不构建无界三角形，而是仅进行模拟，直到值超过`n`，这使得工作量很小。 

然后我们简单地扫描每一行并检查是否有任何条目等于`n`。 这已经足够了，因为如果`n`出现在任何地方，它必须出现在某些行中，其中值仍然小到足以直接计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力全三角形| O(R²) 与大 R | O(R²) 或 O(R) | 太慢了|
 | 有限的帕斯卡一代 | O(R²)，R ≤ 25 | O(R)| 已接受 |

 ## 算法演练

 我们逐行构造帕斯卡三角形，但一旦行太大而无法容纳时，我们就会提前停止`n`。 

1.从行开始`0 = [1]`。 这是三角形的底，并且通常只包含一个值。 如果`n == 1`，我们可以立即返回`(0, 0)`因为这是第一行中唯一的元素。 
2. 对于每个后续行`r`，使用标准递归从上一行构建它。 第一个和最后一个元素始终是`1`，每个内部元素都是前一行中两个相邻元素的总和。 
3. 构造行时，立即检查每个值。 如果任意元素等于`n`， 返回`(r, c)`在哪里`c`是该元素的索引。 尽早退出至关重要，因为一旦我们发现任何有效的事件，问题就可以得到任何答案。 
4. 在构造下一行之前，检查该行中的最大可能值是否仍然可以是`n`或更少。 由于价值增长迅速，一旦所有条目超过，我们就可以安全地停止`n`，由于二项式系数呈指数增长，这种情况发生得非常快。 

正确性来自于这样一个事实：帕斯卡三角形的每个条目都是一个二项式系数，并且每个这样的系数都通过这种构造恰好生成一次。 我们不会跳过三角形的任何区域，我们只是根据一个值界限来限制深度，以确保不会错过超出该范围的有效答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())

if n == 1:
    print("0 0")
    sys.exit()

prev = [1]

if n == 1:
    print("0 0")
    sys.exit()

for r in range(1, 60):
    cur = [1]
    found = False

    if n == 1:
        print(f"{r} 0")
        sys.exit()

    for i in range(1, r):
        val = prev[i - 1] + prev[i]
        cur.append(val)

    cur.append(1)

    for i, v in enumerate(cur):
        if v == n:
            print(r, i)
            sys.exit()

    if min(cur) > n:
        break

    prev = cur

print(-1)
```该解决方案直接使用递归关系构建行。 外部循环将行数限制在安全常数范围内，因为值呈指数增长并且不能长时间保持较小。 每行都是在前一行的线性时间内构造的，并且立即检查每个值是否与`n`。 

一个微妙的细节是，当一行中的所有值超过时，我们会提前终止`n`，因为由于帕斯卡三角形的加法结构，后续行只会进一步增加值。 另一个重要的点是行边界的处理，其中值始终`1`。 这些是明确添加的，不能省略，否则三角形结构就会破裂。

 ## 边缘情况

 对于`n = 1`，算法立即停止在第 0 行。 第一行是`[1]`，因此在任何一代开始之前检查都会成功，并且`(0,0)`被返回。 

对于像这样的小值`n = 2`，算法逐行进行，直到到达第 2 行，即`[1,2,1]`。 该值可在索引处找到`1`，并且提前退出确保没有不必要的计算。 

对于早期行中不存在的值，例如`n = 7`，算法生成行，直到所有条目超过`n`。 一旦发生这种情况，它会安全断裂并返回`-1`，因为随着深度的增加，三角形条目的单调增长导致后面的行不能引入更小的值。
