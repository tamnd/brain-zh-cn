 ## 解决方案
 ## 问题理解

 我们有两个玩家，每个玩家都以十进制形式的整数开头。 亚瑟拥有`a`, 尼基塔拥有`b`。 之后，亚瑟准确地附加`n`十进制数字在他的号码右侧，尼基塔准确地附加`m`他的号码右侧的数字。 这些附加数字可以自由选择。 

完成两次扩展后，所得的两个整数将作为普通整数进行比较。 如果亚瑟的最终数字更大，则亚瑟获胜，如果她的最终数字更大，则尼基塔获胜，否则平局。 

关键在于，两位玩家都试图最佳地选择附加数字，以最大化自己获胜的机会。 由于每个玩家仅控制自己的后缀，因此游戏简化为了解影响力有多大`n`和`m`屈服于克服之间的差异`a`和`b`。 

约束非常大，所有四个值都达到 10^9。 这立即排除了任何试图模拟逐位附加或暴力破解所有后缀的构造。 即使是带有 10^9 位数字的单个数字也不可能明确表示，因此解决方案必须将问题简化为比较封闭形式的大小。 

出现微妙的边缘情况时`a`和`b`很接近，但一名玩家有更多的数字需要附加。 例如，如果`a = 9`,`b = 10`，并且 Arthur 附加了很多数字，而 Nikita 附加了很少的数字，前导结构可能会被后缀长度淹没。 单纯的比较`a`和`b`在这种情况下完全失败，因为它忽略了可以附加多少个数字。 

如果假设玩家总是仅附加 9 或仅附加 0，而不考虑最优性，则会出现另一种失败情况。 正确的推理取决于每个玩家都会选择后缀数字以按字典顺序最大化最终数字，这意味着他们总是在所有附加位置选择 9。 

## 方法

 暴力解释会尝试模拟两个玩家的选择。 对于每个可能的长度的数字串`n`对于亚瑟和`m`对于 Nikita，我们将构建结果数字并进行比较。 这在理论上是正确的，因为每个玩家的最佳选择是在所有可能的后缀中，但可能性的数量是 10^n 和 10^m，即使对于很小的 n 和 m 值，这也是天文数字。 暴力破解立即失败。 

关键的观察是每个参与者的最优策略是确定性的。 由于目标是最大化最终数字，因此每个附加数字都应该是 9。任何较小的数字只能减少该值，而不会在以后提供任何补偿优势，因为更重要的位置占主导地位。 

所以亚瑟的最终数字变成`a`其次是`n`数字 9，尼基塔的变成`b`其次是`m`数字9.

 现在问题简化为比较由串联形成的两个非常大的数字。 我们不是明确地构建它们，而是通过结构进行比较。 如果扩展后位数不同，则以较长的有效长度为准。 如果它们具有相同的有效长度，我们首先按 10 次幂缩放的整数部分进行比较，然后按后缀影响进行比较。 

这将问题简化为比较`a * 10^n + (10^n - 1)`相对`b * 10^m + (10^m - 1)`。 由于直接求幂仅通过 Python 整数仍然是安全的，因此我们依赖于 Python 的任意精度算术或结构化比较逻辑。

 ## 算法演练

 1. 观察两位玩家总是在每个位置上添加数字 9。 这是因为增加任何后缀数字都会增加最终数字，并且与未来的决策没有权衡。 
2. 用两个确定性的最终数字替换游戏状态：Arthur 有`A = a * 10^n + (10^n - 1)`尼基塔有`B = b * 10^m + (10^m - 1)`。 
3. 比较大小`A`和`B`。 不要构造完整值，而是使用 Python 的大整数算术或通过比较数字结构来比较它们。 
4.如果`A > B`，亚瑟获胜。 如果`A < B`，尼基塔获胜。 否则，结果是平局。 

关键的推理步骤是后缀优化完全消除了策略交互。 一旦双方都达到最佳状态，游戏就变成了直接的数字比较问题，没有进一步的选择。 

### 为什么它有效

 每个玩家在每个附加位置的决策都是独立且单调的：增加任何数字都会严格增加最终值，而不管未来的数字如何。 这消除了任何非贪婪结构。 因此，最优策略是固定且唯一的，将游戏分解为两个构造数字的确定性比较。 由于这两种结构对于每个玩家来说都是精确的上限，因此比较它们会给出正确的获胜者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

a, b, n, m = map(int, input().split())

A = a * (10 ** n) + ((10 ** n) - 1)
B = b * (10 ** m) + ((10 ** m) - 1)

if A > B:
    print("Arthur")
elif A < B:
    print("Nikita")
else:
    print("Draw")
```该代码直接实现了每个玩家的最佳最终数字的推导公式。 乘以`10 ** n`将原数左移`n`小数位，以及`(10 ** n - 1)`用 9 填充所有附加数字。 

Python 的整数类型可以安全地处理以下情况下可能出现的非常大的值：`n`和`m`很大，因此不需要手动处理大整数。 

比较是直接整数比较，既正确又高效。

 ## 边缘情况

 一种重要的边缘情况是两名球员具有相同的底座和相同的延伸长度。 用于输入`a = 7, b = 7, n = 3, m = 3`，两者都计算`7 * 10^3 + 999`，产生相同的数字。 该算法自然地处理这个问题，因为两个构造的值是相同的，并且最终的相等检查返回“Draw”。 

另一个微妙的情况是，一名玩家的基数更大，但要附加的数字更少。 为了`a = 1000, b = 1, n = 0, m = 5`, 亚瑟有`1000`，而尼基塔有`1 * 10^5 + 99999 = 199999`。 尽管 Arthur 开头较大，但 Nikita 较长的后缀完全占据主导地位。 该算法捕获了这一点，因为在比较之前应用了十次平移的幂，使得当幅度差异足够大时后缀长度成为主导因素。
