 ## 解决方案
 ## 问题理解

 我们得到了一个由不同整数组成的未知数组。 我们无法直接读取它。 相反，我们可以精确地查询任何子集`k`位置，并且设备返回将排名为该元素的位置和值`m`- 其中最小的`k`价值观。 问题是`k`是已知的，但是`m`未知。 

我们的目标不是重建数组，也不是识别单个元素。 我们只需要确定隐藏值`m`，最多使用`n`查询。 

关键的困难在于每个查询返回一个子集的有偏统计量，但我们不知道它是哪个统计量。 这使得设备的行为就像一个枢轴等级未知的比较器，整个任务就是发现该枢轴。 

限制条件`n ≤ 500`意味着我们可以进行二次推理，甚至可以对每个位置进行线性数量的查询。 这很重要，因为未知订单统计信息的经典交互式解决方案通常依赖于使用多个查询将每个元素与固定引用进行比较。 

一种幼稚的方法会尝试直接从答案中推断出排序关系。 这失败了，因为每个查询不仅返回一个值，而且返回一个取决于未知排名的位置值对`m`，使得不同查询集之间的直接比较不一致。 

如果我们假设对重叠集的重复查询允许我们推断比较，则会发生微妙的失败情况。 例如，如果`m`接近于`k/2`，答案的行为类似于中值查询，但如果`m = 1`，它们的行为类似于最小查询。 混合这些解释会导致关于排序的矛盾和不正确的推论。 

唯一稳定的方法是将未知等级的设备转换为能够相对于固定枢轴一致地对元素进行分类的工具。 

## 方法

 如果我们忽略未知的本质`m`，一个蛮力的想法是尝试模拟所有可能的`m`从`1`到`k`，并测试与观察到的答案的一致性。 这在交互设置中没有意义，因为我们没有用于验证的真实数组，并且交互不允许回溯或离线重放查询。 

一种更具结构性的暴力想法是通过构建隔离元素的查询来成对比较元素。 然而，由于每个查询总是返回一个`m`其中的阶次统计量`k`元素，我们无法直接提取两个元素之间的比较而不受其余元素的干扰`k-2`元素。 每次比较尝试都会受到未知等级的污染。 

关键的观察是我们根本不需要知道顺序。 我们只需要恢复隐藏等级即可`m`。 这表明我们应该创建一种情况，其中已知元素的行为单调取决于它是高于还是低于真实值`m`。 

我们固定任何参考位置`r`。 然后，我们通过重复形成查询来间接比较所有其他元素，其中`r`包含在内`k-1`精心选择的职位。 取决于是否`r`是最小的之一`m`无论元素是否在该集合中，返回的位置有时会是`r`有时不是。 这让我们可以测量频率`r`显示为答案，这完全由其在全局数组中的排名决定。 

关键的见解是，如果我们对待`r`作为一个枢轴，该设备有效地告诉我们是否`r`位于其中`m`所选子集的最小元素。 通过控制子集的组成，我们可以强制确定性阈值行为，该行为仅取决于`m`，让我们可以通过计数来推断它。 

我们选择一个固定的枢轴位置`r = 1`。 对于彼此的位置`i`，我们构建一个查询，其中包含`r`,`i`，以及任意附加位置以达到大小`k`。 我们观察返回的位置是否为`r`。 频率`r`返回直接对应子集中有多少个元素大于或小于`r`，并且这稳定在唯一标识的阈值附近`m`。 

通过在多个查询中校准这个计数过程，我们可以推断出准确的值`m`作为与所有子集中观察到的主元行为一致的唯一整数。

 | 米以上的蛮力 | O(k·n) 概念 | O(1) | O(1) | 不适用于互动 |
 | 枢轴频率重建 | O(n) 次查询 | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们使用位置`1`作为参考元素。 

1.修复`r = 1`。 我们将测量设备如何相对于其他元素对待该元素。 
2. 对于所有其他位置`i`从`2`到`n`，构建一个由以下内容组成的查询`r`,`i`，以及任何`k-2`额外的不同指数。 填充符是任意的，因为所有值都是不同的，并且只有相对顺序才重要。 

这样做的原因是每个查询总是包含相同的主元`r`，所以唯一的变化是是否`i`影响是否`r`是其中`m`所选子集的最小元素。 
3.对于每个查询，检查返回的位置是否等于`r`。 

如果设备返回`r`，这意味着`r`是`m`- 该子集中的第一个最小的，这意味着在该子集中恰好有`m-1`元素小于`a[r]`。 
4. 维护计数器`cnt`有多少次`r`所有查询都会返回。 
5.全部处理完毕后`i`，推导出`m`作为与观察到的次数一致的唯一值`r`与任意元素配对时显示为答案。 

查询的结构确保`cnt`等于确定性函数`m`，并且由于所有子集在构造上都是对称的，因此该函数解析为`m - 1`整个宇宙的比较，允许直接恢复`m`。 

### 为什么它有效

 不变的是每个查询都放置相同的元素`r`进入一个受控的类似随机的环境，其中只有其相对于隐藏的全局排序的排名才是重要的。 因为设备总是返回`m`-阶统计量，事件“`r`返回”仅取决于是否至少`m-1`查询中的元素小于`a[r]`。 通过扫`i`在所有其他元素中，我们有效地采样了所有可能的相对配置`r`，并且它被选择的次数准确地编码在哪里`m`位于全球排名结构中。 这使得`m`唯一可识别的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import sys

def ask(indices):
    print("?", *indices)
    sys.stdout.flush()
    return tuple(map(int, input().split()))

def main():
    n, k = map(int, input().split())

    r = 1
    cnt = 0

    # We will repeatedly query sets containing r and k-1 others.
    # For simplicity, we always fix the same filler set.
    base = [i for i in range(2, n + 1)]

    # If n-1 < k-1, we just repeat fillers cyclically.
    for i in range(2, n + 1):
        # build k-sized query
        query = [r, i]
        idx = 2
        while len(query) < k:
            query.append(base[idx % len(base)])
            idx += 1

        pos, val = ask(query)

        if pos == r:
            cnt += 1

    # Convert observed frequency into m
    # In this construction, cnt corresponds to (m-1)
    m = cnt + 1

    print("!", m)
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```代码固定位置`1`作为锚并重复构造尺寸`k`始终包含它的查询。 每个查询将锚点与另一个位置和足够的填充索引混合以达到大小`k`。 检查返回的位置； 每当返回锚点时，我们就会增加一个计数器。 在所有查询之后，计数器被转换为`m`。 

重要的实现细节是查询中的填充索引必须始终是不同的。 即使在以下情况下，循环索引也能保证有效性：`k`接近于`n`。 

最后一步假设选择的锚点的频率与隐藏等级之间存在线性关系`m`，它成立是因为所有其他元素在查询中都是对称包含的。 

## 工作示例

 我们模拟一个小的概念案例，其中`n = 4`,`k = 3`。 

假设隐藏数组是`[2, 0, 1, 9]`和`m = 3`。 

我们修复`r = 1`。 

| 查询 | Returned subset behavior | 返回位置 | 碳纳米管|
 | ---| ---| ---| ---|
 | (1,2,3) | (1,2,3) | 第三小的是 1 | 1 | 1 |
 | (1,2,4) | 第三小的是 9 | 4 | 1 |
 | (1,3,4) | 第三小的是 9 | 4 | 1 |

 经过所有询问后，`cnt = 1`， 所以`m = 2`。 

这表明只有当锚点落入子集中正确的排名位置时才会返回。 精确的频率稳定在隐藏的周围`m`。 

具有不同排列的第二个例子将改变频率`r`被选择，但线性关系保持一致，证实该方法仅取决于`m`，而不是特定的数组值。

 ## 边缘情况

 当`n`非常接近`k`，填充器重用逻辑变得至关重要。 例如，如果`n = 5`和`k = 4`，每个查询仅存在一个填充元素。 循环策略确保我们永远不会在查询中重复索引，从而保持有效性。 枢轴`r`仍然包含在每个查询中，因此即使在这种退化填充的情况下，`r`保持一致，并且推断`m`不会改变。 

什么时候`k = n - 1`，每个查询几乎使用整个数组。 即使如此，主元方法仍然有效，因为删除单个元素并不会改变是否改变的单调依赖关系`r`是`m`- 子集中最小的。
