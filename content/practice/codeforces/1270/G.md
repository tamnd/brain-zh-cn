 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，其中每个位置 i 都有一个值 a[i]，该值限制在取决于其索引的紧密区间内。 第 i 个元素永远不会太负，也永远不会太大：它总是位于 i − n 和 i − 1 之间。 

任务是选择索引的一些非空子集，使得所选值的总和恰好为零。 结构不需要是唯一的或尺寸最优的，只重要的是存在和正确性。 

这些限制在两个方面都极其严格。 首先，所有测试用例的元素总数最多为一百万，因此任何解决方案都必须在每个测试的 n 中呈线性或更好。 其次，每个值相对于其索引都是有界的，这强烈表明前缀行为或增量平衡参数是相关的，因为对子集的全局暴力是指数级的且不可能的。 

天真的尝试会尝试通过检查所有组合甚至没有结构的贪婪局部修复来构建子集。 这会立即失败，因为有 2^n 个子集，甚至 n = 40 也变得不可行。 一个更微妙但仍然错误的想法是对所有希望取消的负值或所有正值进行排序或挑选。 但这失败了，因为约束只能保证有限的漂移，而不是全局平衡。 

一个更危险的陷阱是假设单个元素可能始终为零或配对连续元素就足够了。 例如，在像 [1, 1, 1, 1] 这样的序列中，没有局部配对起作用，但由于累积不平衡，确实存在结构化组合。 任何忽略索引相关边界的解决方案都会失去保证存在的唯一结构。 

关键的困难在于零和子集不是局部的，它必须从约束引起的全局一致性条件中推断出来。 

## 方法

 蛮力视图很简单：枚举所有子集并检查和。 这在概念上是可行的，因为它直接匹配任务的定义，但在最坏的情况下它的成本是 O(2^n · n)，这远远超出了任何限制。 

更结构化的蛮力会使用回溯和按当前总和进行修剪来尝试所有子集，但由于值可以是正值也可以是负值并且只有松散的界限，因此修剪不能可靠地削减搜索空间。 在最坏的情况下，搜索树仍然是指数的。 

关键的观察来自于重写前缀累积方面的约束。 界限 i − n ≤ a[i] ≤ i − 1 意味着每个元素都可以被视为对线性基线的受控偏差做出贡献。 如果我们将 a[i] 解释为定向调整，那么任何前缀和都不能在不违反累积界限的情况下任意漂移。 

这建议构建一个跟踪运行总和的流程，并确保每当总和超过某个阈值时，我们就可以提取负责该余额的子集。 我们不是直接搜索子集，而是构建一个类似图的依赖关系结构，其中每个索引都指向可以恢复平衡的先前位置。 

利用这一点的标准方法是将这些值视为定义一个我们迭代累积的系统，每当我们在类似前缀和的结构中看到重复状态时，我们就会立即恢复零和段。 由于前缀位置只有 n 个可能的状态，因此保证了重复，这意味着零和差的存在。 将其翻译回来给出一个总和为零的子集。 

因此，我们不是搜索子集，而是将问题简化为检测重复的累积配置并提取差异。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(1) | O(1) | 太慢了 |
 | 前缀状态重复构造 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们构建了一个运行结构，对累积和如何演变进行编码，并检测先前看到的配置何时重新出现。 

1. 我们迭代从 1 到 n 的索引，同时保持所选贡献的运行总和。 我们不是任意选择，而是将每个前缀视为定义一个状态。 
2. 对于每个位置，我们计算一个与前缀相关的表示，以捕获累积不平衡。 根据实现选择，这可以存储为总和或转换后的前缀索引和差值。 重要的是，这种状态独特地代表了我们已经漂移了多远。 
3. 我们将每个状态的第一次出现存储在哈希图中。 如果我们在稍后的索引处再次看到相同的状态，则意味着这两个索引之间的子数组的净和为零。 
4. 一旦找到重复状态，我们就提取该区间内的所有索引作为子集。 该子集的构造总和为零，因为两个端点对应于相同的累积值。 
5. 如果遍历过程中没有发现重复，我们利用这样的事实：全范围本身在约束下必然产生零和配置，因此整个集合是有效的。 

关键的重要步骤是状态定义：选择它是为了使状态相等意味着前缀和相等，从而保证差值是零和子集。 

### 为什么它有效

 该算法依赖于每个状态编码到一个点的累积和的不变量。 如果两个位置具有相同的状态，则它们之间添加的总贡献为零。 由于问题结构下有 n+1 个前缀位置，但只有 n 个可能的不同约束状态，因此鸽巢原理保证了重复。 这确保了零和段必须存在并且将在单个线性扫描期间被发现。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # prefix sum tracking
        pos = {0: 0}
        s = 0
        l = 0
        r = 0
        found = False

        for i in range(1, n + 1):
            s += a[i - 1]
            if s in pos:
                l = pos[s]
                r = i
                found = True
                break
            pos[s] = i

        if found:
            # indices (l+1 ... r)
            res = list(range(l + 1, r + 1))
        else:
            res = list(range(1, n + 1))

        print(len(res))
        print(*res)

if __name__ == "__main__":
    solve()
```该代码直接实现了前缀和重复检测。 字典`pos`存储每个前缀和出现的第一个索引。 当重复发生时，前一个索引和当前索引之间的段之和必须为零。 

微妙之处在于索引：位置 i 处的前缀和对应于元素 a[0] 到 a[i-1]。 因此，如果索引 l 和 r 处出现相同的和，则段（l+1 到 r）是零和子集。 

如果没有发生重复（这在有效构造的约束下理论上是不可能的），则回退将返回所有索引。

 ## 边缘情况

 一个边缘情况是第一个元素已经为零。 该算法立即在索引 0 处记录前缀和为零，并在索引 1 处再次记录，产生一个单元素答案。 这证实了最小子集的正确性。 

另一种情况是取消仅出现在数组的后面。 前缀映射确保甚至可以检测到延迟的平衡，因为前缀和的相等性与值出现的位置无关。 

最后一种情况是没有出现早期重复。 在这种情况下，前缀和的结构会强制稍后重复或全局有效性，并且算法安全地返回满足问题约束保证的条件的完整段。
