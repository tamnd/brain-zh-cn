 ## 解决方案
 ## 问题理解

 我们给出了几个测试用例，每个测试用例都提供了一个整数数组。 任务是确定该数组是否存在一个连续的段，其分布与其长度相比足够大。 更准确地说，我们想要一个子数组，其中最大元素和最小元素之间的差至少与该子数组中元素的数量一样大。 

对于每个测试用例，我们必须输出不存在这样的子数组，或者输出满足此条件的任何有效子数组。 

所有测试用例的总数组大小的限制最多为 200,000，这排除了每个测试用例的任何二次或更差的方法。 重新计算每个子数组的最小值和最大值的解决方案每个测试用例大约需要 O(n^2) 工作，这会立即超时。 这推动我们走向线性或近线性结构。 

一个简单但重要的边缘情况是所有元素都相同。 在这种情况下，每个子数组的 max 减去 min 等于 0，而任何长度至少为 1 的子数组都需要至少与其长度的差值。 所以答案永远是不可能的。 另一个边缘情况是有效子数组仅存在于数组的末尾，如果不注意子数组的构造方式，贪婪的“中间聚焦”方法可能会错过这种情况。 

## 方法

 一种直接的方法是尝试每个子数组并计算其最小值和最大值。 对于每对端点，我们扫描该段并评估条件是否成立。 这是正确的，因为它准确地检查了问题的定义。 然而，对于大小为 n 的数组，有 O(n^2) 个子数组，每个子数组都需要 O(n) 时间来计算，从而导致总复杂度为 O(n^3)。 即使通过优化来增量地维持最小值和最大值，我们仍然处于 O(n^2)，这对于 n 高达 200,000 来说太慢了。 

关键的观察是我们实际上不需要考虑所有子数组。 我们只需要找到一个最大值和最小值之间的差距与其长度相比足够大的值。 我们可以围绕数组表现出较大跳跃的两个位置贪婪地构造一个子数组，而不是考虑任意间隔。 

考虑任意一对索引 i 和 j，使得绝对差 |a[i] - a[j]| 很大。 如果我们取从 i 到 j 的子数组，其最大值至少为 max(a[i], a[j])，最小值至多为 min(a[i], a[j])。 长度为 j - i + 1。如果与索引距离相比值差异足够大，我们立即获得有效答案。 

这将问题从搜索子数组转移到检查是否存在足够“陡峭”的对。 由于我们只需要一个有效的子数组，因此我们可以寻找一个构造性条件：如果我们对极值进行排序或在概念上跟踪极值，那么当数组包含在短距离内强制出现较大值差距的局部配置时，我们始终可以导出有效的段。 

标准解决方案进一步简化了这一点：在按值对索引进行排序后检查相邻元素就足够了，或者推断如果不存在这样的子数组，则该数组在精确意义上一定是“太平坦”，这意味着所有元素都相等。 这导致了一个直接的构造：如果我们找到两个值差至少为索引距离的位置，我们就会输出该段。

 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 对于每个测试用例，扫描数组并考虑由位置对定义的候选子数组，其中较大的值差异可能会补偿它们的距离。 最简单的候选者来自于我们遍历数组时比较元素。 
2. 在迭代时维护迄今为止看到的最小和最大值及其位置。 目标是检测当前位置是否可以与先前看到的极值形成有效的线段。 
3. 在索引 i 处，将 a[i] 与目前为止看到的当前最小值和最大值进行比较。 如果a[i]远大于最小值或远小于最大值，我们测试它们位置之间的线段是否满足条件max - min ≥ length。 
4. 如果任一条件成立，我们立即输出相应的段，因为任何有效的子数组就足够了。 
5. 如果我们完成扫描后没有找到任何有效的对，则得出结论：不存在感兴趣的子数组。 

### 为什么它有效

 任何有效的子数组都必须在线段的某些两个端点处具有最大值和最小值。 当从左到右扫描时，这些端点对应于某个较早的位置和当前索引。 如果存在有效段，当我们在扫描中到达它时，它的端点之一最终将是正确的边界。 此时，存储在另一侧的极值保证我们能够检测到该情况。 这确保了我们不会错过任何候选段，因为每个有效子数组在遍历期间都会由其最终元素见证。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        min_val = a[0]
        max_val = a[0]
        min_pos = 0
        max_pos = 0

        found = False
        ans_l = ans_r = -1

        for i in range(n):
            if i == 0:
                continue

            # try extending with current element as right endpoint
            if a[i] < min_val:
                min_val = a[i]
                min_pos = i

            if a[i] > max_val:
                max_val = a[i]
                max_pos = i

            # check using current extremes
            if max_val - a[i] >= (i - max_pos + 1):
                ans_l, ans_r = max_pos, i
                found = True
                break

            if a[i] - min_val >= (i - min_pos + 1):
                ans_l, ans_r = min_pos, i
                found = True
                break

        if found:
            print("YES")
            print(ans_l + 1, ans_r + 1)
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```该实现在从左到右扫描时保持运行极值及其位置。 关键细节是我们始终将当前元素与已知的最小值和最大值进行比较，因为任何以 i 结尾的有效子数组必须使用其中之一作为其相反端点。 

通过在内部存储从零开始的位置并仅在输出时转换为从一开始的索引来仔细处理索引。

 ## 边缘情况

 对于所有值都相同的数组，该算法将 min 和 max 初始化为相同的值，并且永远找不到 max 减去 min 可以增长的段。 每次比较都会失败，因为当所需长度增加时，值差异保持为零。 扫描完成并正确返回 NO。 

对于大小为 2 的小数组，如果值不同，则该段立即有效，因为差异至少为 1，并且仅当差异足够大时，所需的阈值也是 2。 该算法检查唯一可能的段并直接返回它，与条件完全匹配。 

对于严格递增的序列，即使 max 减去 min 随着时间的推移而增长，子数组长度也会以相同的速率增长，因此不等式永远不会转向有利于有效性的方向。 该算法不断更新极值，但从未遇到值差距主导索引距离的段，从而导致正确的“否”结果。
