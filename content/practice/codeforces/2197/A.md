 ## 解决方案
 ## 问题理解

 我们给定一个整数$x$，我们想要计算有多少个整数$y$满足一个非常具体的平衡条件：如果你采取$y$减去它的数字之和，你正好落在$x$。 换句话说，每个有效数字$y$与相比“多付”$x$，而多付的金额恰好是$y$。 

所以任务不是构建$y$，但要计算每个存在多少个这样的结构$x$。 每个测试用例询问：在所有整数中，有多少个不同的$y$减去它们的数字和后会塌陷到相同的值吗？ 

约束条件达到$x \le 10^9$和$t \le 500$。 对所有可能的天真扫描$y$立即不可能，因为即使是单个测试用例也需要检查潜在的数十亿候选者。 即使只扫描附近$x$不受多远限制是不安全的$y$可以漂移。 

一个关键的结构观察是转变$y \mapsto y - d(y)$最多只能将数字向下移动位数乘以 9。对于 10 位数字，数字和最多为 90，因此$y$不能大于大约 90$x$。 这使得搜索空间受到严格限制。 

当出现微妙的边缘情况时$x$很小。 例如，如果$x = 1$，那么潜在的候选人$y$需要满足$y - d(y) = 1$。 尝试较小的值表明符合条件的数字很少，并且很容易错误地假设没有或很多而不检查确切的约束关系。 

## 方法

 蛮力策略是迭代所有可能的$y$达到某个大的限制并测试是否$y - d(y) = x$。 这是正确的，但完全不可行，因为$y$范围可达$10^9 + 100$我们将为每个候选人执行数字和计算。 这导致大约$O(10^9)$每个测试用例的操作次数，这远远超出了任何合理的限制。 

关键的见解是颠倒等式。 而不是从$y$，我们从$x$并询问什么值$y$可能会映射到它。 如果$y - d(y) = x$， 然后$y = x + d(y)$。 这看起来是循环的，但它揭示了一个关键的约束：$y$很小并且至多有界$9 \cdot 10 = 90$。 

所以我们可以尝试所有可能的数字和$s$在一个小范围内。 如果我们修复$s = d(y)$， 然后$y = x + s$。 我们简单地检查数字和是否$x + s$等于$s$。 每个有效$s$恰好贡献了一个有效的$y$。 

这将问题从潜在的数十亿候选者减少到每个测试用例最多 100 个检查，每个检查都涉及数字和计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力胜过一切$y$|$O(N \cdot \log N)$|$O(1)$| 太慢了 |
 | 尝试所有数字和$s \in [0, 100]$|$O(100 \cdot \log x)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 对于给定的$x$，观察任何有效的$y$必须满足$y = x + s$， 在哪里$s = d(y)$。 自从$y$最多有 10 位数字，$s \le 90$，所以我们只需要尝试小范围的候选数字和。 
2. 迭代所有可能的值$s$从 0 到 100。上限稍微放宽以避免边缘错误，但只有高达 90 的值才能真正成功。 
3. 对于每个$s$, 计算$y = x + s$。 这是该数字和的唯一可能的候选者。 
4. 计算数字和$y$，表示为$d(y)$。 这一步验证我们对数字和的假设是否一致。 
5.如果$d(y) = s$， 然后$y$是一个有效的友好号码。 增加答案。 
6.检查完所有可能的情况后$s$，输出总计数。 

这个枚举起作用的原因是每个有效的$y$与其数字和唯一相关$s$，并且我们确保没有候选人被遗漏或重复计算。 

### 为什么它有效

 每个解决方案$y$恰好导出一个值$s = d(y)$，并且必须满足$y = x + s$。 我们对所有可能的循环$s$保证我们重建每一位候选人$y$这可能满足方程。 由于数字和是有界的并且单射决定之间的偏移$x$和$y$，搜索空间既完整又非冗余。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def digit_sum(n):
    s = 0
    while n > 0:
        s += n % 10
        n //= 10
    return s

t = int(input())
for _ in range(t):
    x = int(input())
    ans = 0
    
    for s in range(0, 100):
        y = x + s
        if digit_sum(y) == s:
            ans += 1
    
    print(ans)
```该代码将数字和计算分离到辅助函数中，因为它被重复调用。 循环结束$s$核心思想是：每个$s$被视为数字和的假设$y$，我们直接验证一下。 

100 的界限是安全的，因为 10 位数字的最大可能数字和是 90，并且$x \le 10^9$保证最多 10 位数字$y$。

 ## 边缘情况

 当$x = 1$，算法检查所有$s \in [0, 99]$，产生候选人$y = 1 + s$。 这些候选人都不满足$d(y) = s$，因为与线性移位相比，数字和增长得太慢。 算法正确返回 0。 

当$x = 999{,}999{,}999$，候选人的范围大约为$10^9 + 100$。 即使在这里，数字总和仍以 90 为界，因此只有一小部分班次可以工作。 该循环仍然捕获所有可能性，因为每个有效的$y$必须位于枚举窗口内。 

什么时候$x$是 9 的倍数或包含许多尾随 9，附近数字的数字和波动较大，但仍保持在有界范围内。 该算法不依赖单调性，仅对所有可行的数字和进行详尽的检查，因此这些情况可以自然处理，无需修改。
