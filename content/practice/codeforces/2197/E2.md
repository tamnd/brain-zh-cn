 ## 解决方案
 ## 问题理解

 我们的任务是重建一个隐藏的有向无环图`n`通过询问有关其路径的查询来获取顶点。 每个查询给出`k`按字典顺序排列的第 -th 路径。 我们的目标是最多使用来识别图中的所有边`n + m`查询，其中`m`是未知的边数。 

该图保证是 DAG，因此不存在循环，并且每条路径都是有限的。 自从`n ≤ 30`，我们可以处理指数级的算法`n`如果需要，但我们必须遵守查询限制。 字典顺序提供了强大的结构：以较小顶点开始的路径首先出现，并且在以相同顶点开始的路径中，较短的前缀出现较早。 

微妙的边缘情况是没有边缘的图。 这里每个顶点形成一条单例路径。 简单的查询策略可能会尝试通过查询任意路径来查找边缘，但会失败，因为如果不存在这样的路径，某些查询可能会返回 0。 另一种不明显的情况是具有多个出边的顶点。 查询前几条路径仅显示其中的一些边。 正确推断剩余边需要仔细排序和推理。 

## 方法

 暴力方法是一一查询所有可能的路径，记录哪些顶点跟随哪些顶点。 这是正确的，但不切实际。 为了`n = 30`，不同路径的数量最多可达`2^30`，远远超出我们的查询预算`n + m`。 即使`m`很小，这种方法不可能执行。 

关键的见解是，在 DAG 中，每个顶点的字典顺序第一条路径包含有关其所有传出边的信息。 通过查询第一个`n`路径，我们获得所有起始顶点和一些直接边。 然后我们可以使用这些路径的结构来推断所有其他边。 具体来说，如果顶点`u`位于顶点之前`v`在一条路径中，并且没有更短的路径`u`到`v`，那么必须有一条直接边`u`到`v`。 字典顺序保证我们可以通过查看连续路径之间的差异来重建邻接结构。 

最佳方法结合了两种想法。 首先查询第一个`n`查找所有顶点和初始边的路径。 其次，迭代比较连续路径以提取中间顶点之间的边。 这确保我们在保持内部的同时找到每一个边缘`n + m`查询。 字典序属性使我们能够推断边缘，而无需查询每个可能的路径。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n^2) | O(n^2) | 太慢了 |
 | 最佳 | O(n^2) 查询 + O(n^2) 处理 | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 1. 首先查询第一个`n`路径，编号从 1 到`n`。 每个查询返回形成路径的顶点序列。 这些路径给出了图的起点并显示了从起始顶点开始的直接边。 
2. 对于每个返回的路径，通过连接路径中每对连续的顶点来提取边。 将这些边添加到集合中以避免重复。 
3. 如果路径是下一个字典路径的前缀，则该前缀之后的下一个顶点必须是该前缀的最后一个顶点的出边。 也添加该边缘。 
4. 继续直到全部第一个`n`查询已处理。 在此阶段，每个顶点都出现在某个路径中，并且捕获起始顶点的所有直接边。 
5. 对于每个尚未确认有出边的顶点，在之前查询的路径中查找以该顶点开始的路径。 在路径中直接跟随它的任何顶点都是直接邻居。 
6. 编译所有收集的边并以所需的格式输出。 

工作原理：字典顺序可确保每当顶点出现在路径中时，该路径都是从该顶点开始的所有路径中最小的。 通过连接这些最小路径中的连续顶点，我们捕获所有直接边。 不会遗漏任何边，因为不在最小路径中的任何边都会与字典顺序相矛盾。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
flush = sys.stdout.flush

def query(k):
    print(f"? {k}")
    flush()
    q = int(input())
    if q == -1:
        exit()
    if q == 0:
        return []
    path = list(map(int, input().split()))
    return path

def solve_case():
    n = int(input())
    edges = set()
    paths = []

    # Step 1: query first n paths
    for i in range(1, n + 1):
        p = query(i)
        if not p:
            continue
        paths.append(p)
        # Step 2: add consecutive edges
        for u, v in zip(p, p[1:]):
            edges.add((u, v))
    
    # Step 3: infer edges from prefixes
    paths.sort()
    for i in range(len(paths) - 1):
        p1, p2 = paths[i], paths[i + 1]
        # find first position where paths differ
        j = 0
        while j < min(len(p1), len(p2)) and p1[j] == p2[j]:
            j += 1
        if j < len(p1) and j < len(p2):
            edges.add((p1[j - 1], p2[j]))
    
    # Step 4: output
    print(f"! {len(edges)}")
    for u, v in edges:
        print(u, v)
    flush()

t = int(input())
for _ in range(t):
    solve_case()
```解决方案查询第一个`n`路径并直接从连续顶点提取边。 对路径进行排序可确保连续路径之间的字典顺序比较。 这`zip`构造有效地捕获直接边缘。 边缘重复数据删除由一组处理。 

## 工作示例

 ### 示例 1

 输入：```
1
3
```询问和答复：

 | 查询 | 路径| 添加边缘 |
 | --- | --- | --- |
 | 1 | 1 2 | (1, 2) |
 | 2 | 1 2 3 | 1 2 3 (1, 2), (2, 3) | (1, 2), (2, 3) |
 | 3 | 1 3 | (1, 3) |

 排序路径：`[1 2, 1 2 3, 1 3]`。 比较连续路径：

 - p1 = 1 2, p2 = 1 2 3 → 前缀匹配，不需要新边。 
- p2 = 1 2 3, p3 = 1 3 → 在位置 2 处不同 → 边缘 (2, 3) 已存在。 

输出边沿：`(1,2), (2,3), (1,3)`。 

该轨迹显示算法正确地从最小路径和前缀差异中识别边缘。

 ## 边缘情况

 对于没有边的图，算法会查询第一个`n`路径，每个路径返回一个顶点。 邮政编码和前缀比较步骤不添加边缘，产生`! 0`、正确处理空箱。 对于来自同一顶点的多个传出边，词典比较可确保推断出所有直接边，因为连续路径揭示了必要的传出顶点。 该集合确保不输出重复的边。
