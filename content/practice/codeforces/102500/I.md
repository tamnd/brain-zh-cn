 ## 解决方案
 ## 问题理解

 我们有一系列卡牌稀有度值。 序列应按非降序排序，但一个连续的段可能已颠倒。 任务是找到一个片段，当反转一次时，可以使整个序列排序。 如果不存在这样的部分，我们必须报告这是不可能的。 任何有效的段都是可接受的。 

输入包含卡片的数量及其当前顺序。 输出是要反转的段的从 1 开始的左侧位置和右侧位置。 允许长度为 1 的段，因为反转一个元素会使数组保持不变。 

输入的大小是主要的挑战。 对于多达 1,000,000 个值，尝试许多可能的分段的算法是不切实际的。 检查每个可能的间隔将需要大约 n2 个候选者，在最坏的情况下大约需要 10^2 个检查。 即使解决方案在每个可能的时间间隔内执行少量工作，也会超出可用时间。 预期的方法必须对数组进行固定次数的处理，从而给出 O(n) 的解决方案。 

一些边缘情况可能会破坏仅考虑明显无序的解决方案。 

例如，一个已经排序的数组，例如：```
1 2 3
```有答案：```
1 1
```仅搜索递减部分并假设必须找到一个的解决方案将错误地打印不可能。 

另一个棘手的情况是当反向段接触数组边界时：```
3 2 1 4
```正确答案是：```
1 3
```仅检查由递增值包围的段的解决方案可能会错过这一点，因为反转部分之前没有元素。 

第三种情况涉及相等的值：```
1 2 2 1 2
```正确答案是：```
3 4
```坏区开始处的两个相等的值不会产生下降。 将每个相等对视为问题的解决方案可能会选择不正确的段。 

## 方法

 一种简单的方法是尝试每个可能的连续段，将其反转，然后检查结果数组是否已排序。 这是正确的，因为每个可能的答案都经过明确测试。 有 n(n+1)/2 个可能的段，如果之后比较整个数组，检查一个段需要 O(n) 时间。 总工作量为 O(n³)，这远远超出了 n = 1,000,000 时所能完成的工作量。 即使改进检查步骤仍然留下太多候选片段。 

问题的结构提供了更强有力的观察。 如果已排序的数组有一个段被反转，则该段之外的所有内容都保持排序。 在段内，顺序必须在反转之前完全递减。 这意味着数组中唯一有趣的部分是序列停止非递减的第一个位置和序列停止非递减的最后一个位置。 

我们可以找到最长的已排序前缀和最长的已排序后缀。 他们之间的一切，是唯一可以逆转的片段。 识别出这个候选片段后，我们只需要验证两个属性。 里面一定是非增的，因为反转后会变成增的。 紧邻段外部的值必须在反转后适合，这意味着新的左边界不能小于其之前的元素，并且新的右边界不能大于其之后的元素。 

蛮力之所以有效，是因为它探索了每一个可能的受损区域，但会失败，因为可能性的数量太大。 观察到一次反转恰好产生一次单调破坏，使我们能够在线性时间内找到唯一可能的区域。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) 额外 | 已接受 |

 ## 算法演练

 1. 从头开始扫描，直到序列减少的第一个索引。 该索引之前的所有内容都已经是有效的排序前缀。 如果不存在这样的索引，则对整个数组进行排序，并且反转第一个元素是有效的答案。 
2. 从末尾开始扫描，直到从右向左移动时序列递减的第一个索引。 该索引之后的所有内容都已经是有效的排序后缀。 这两个位置之间的间隔是唯一可能的反转段。 
3. 检查候选区间从左到右不递增。 反转后，区间内的每个值都必须变为非减值。 
4. 检查候选区间与其外部已排序部分之间的联系。 如果区间之前有一个元素，则它必须小于或等于区间的新第一个元素。 如果间隔后面有一个元素，则间隔的新最后一个元素必须小于或等于下一个元素。 
5. 如果所有检查都通过，则使用基于 1 的索引输出候选边界。 否则，报告没有任何一次反转可以对数组进行排序。 

这样做的原因是反转一个段只会改变该段内的顺序。 段外部的每个元素都保持其相对位置，因此那些外部部分必须已经排序。 第一个和最后一个减少准确地确定了反转块必须开始和结束的位置。 在该块内，反转将递减序列更改为递增序列，因此验证递减属性和两个边界连接足以证明整个数组已排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    left = 0
    while left + 1 < n and a[left] <= a[left + 1]:
        left += 1

    if left == n - 1:
        print("1 1")
        return

    right = n - 1
    while right - 1 >= 0 and a[right - 1] <= a[right]:
        right -= 1

    for i in range(left, right):
        if a[i] < a[i + 1]:
            print("impossible")
            return

    if left > 0 and a[left - 1] > a[right]:
        print("impossible")
        return

    if right + 1 < n and a[left] > a[right + 1]:
        print("impossible")
        return

    print(left + 1, right + 1)

if __name__ == "__main__":
    solve()
```第一个循环找到最长排序前缀的末尾。 循环恰好在第一个反转处停止，因为任何有效的反转部分都必须包含该反转。 

第二个循环查找已排序后缀的开头。 这两个指数现在描述了唯一可能被逆转的部分。 

内部验证使用`a[i] < a[i + 1]`作为失败条件，因为该段必须是非递增的。 允许相同的值，这对于具有重复稀有度的情况是必要的。 

边界检查与反转之后的值进行比较，而不是之前的值。 反转段的最左边的值成为段内的最大值，最右边的值成为段内的最小值。 这就是为什么比较使用`a[right]`对于左边界和`a[left]`为右边界。 

所有指数在处理时都保持从零开始的位置。 只有最终输出才会将它们转换为所需的从 1 开始的位置。 

## 工作示例

 对于第一个样本：```
10 13 19 19 15 14 20
```| 变量| 价值|
 | --- | --- |
 | 第一递减位置 | 2 |
 | 最后减持仓位 | 5 |
 | 候选部分| [2, 5] |
 | 段检查 | 19, 19, 15, 14 是非增 |
 | 边界检查 | 通行证 |
 | 输出| 3 6 |

 前缀`10 13 19`已经排序并且后缀`20`已经排序了。 反转中间部分会产生`10 13 14 15 19 19 20`，确认候选区间正是损坏部分。 

对于第二个样本：```
9 1 8 2 7 3
```| 变量| 价值|
 | --- | --- |
 | 第一递减位置 | 0 |
 | 最后减持仓位 | 5 |
 | 候选部分| [0, 5] |
 | 段检查 | 失败，因为 1 < 8 |
 | 输出| 不可能|

 整个数组需要反转，但在反转之前它并没有减少。 由于所需的内部属性失败，因此任何单一的反转都无法修复它。

 ## 边缘情况

 对于已经排序的数组：```
1 2 3
```第一次扫描到达末尾但没有发现反转。 算法立即返回`1 1`，因为允许反转单张牌并且序列不变。 

对于触及开头的反转：```
3 2 1 4
```第一个递减位置是索引 0，后缀扫描找到索引 2。候选段是`[0,2]`。 它是非递增的，并且没有左边界可供检查。 右边界检查比较`3`和`4`，通过了，所以算法输出`1 3`。 

对于重复值：```
1 2 2 1 2
```第一个反转出现在第二个反转之间`2`和`1`，所以候选段是`[2,3]`。 该段`2 1`是不增加的，将其反转可以得到`1 2`，得到一个排序数组。 接受相等的相邻值，因为排序允许重复值。
