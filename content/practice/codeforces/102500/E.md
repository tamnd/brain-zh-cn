 ## 解决方案
 ## 问题理解

 克莱尔已完成四次求解，还剩最后一次求解。 她的最终得分是通过全部五次，去除最快的解决方案和最慢的解决方案，然后对剩余的三次进行平均来计算的。 目标是确定她最后一次求解的速度有多慢，同时将最终得分保持在目标值以内。 

输入给出了四个已知的求解时间和最大可接受的最终平均值。 输出描述了最大可能的第五求解时间。 如果即使是非常好的第五解也无法达到目标，那么答案是`impossible`。 如果第五次求解可以任意慢并且目标仍然满足，则答案是`infinite`。 

只有四个已知时间，因此该问题不需要数据结构或对许多值进行搜索。 输入量小意味着主要挑战是找到未知的第五次与最终分数之间的数学关系。 对可能的时间进行强力模拟是不可能的，因为答案需要精确的两位小数精度，并且可能值的范围很大。 相反，解决方案应将评分规则简化为直接公式。 

棘手的情况来自这样一个事实：第五个解决方案可以成为最佳解决方案或最差解决方案，从而改变删除的值。 

例如：```
6.00 7.00 8.00 9.00
8.00
```正确的输出是：```
infinite
```如果最后一次求解非常大，则将其作为最差时间丢弃。 剩余分数基于 6、7、8，其平均值为 7.00。 由于这已经达到了目标，因此任何最后的解决方案都有效。 总是假设第五次仍保留在平均值中的粗心解决方案将错误地拒绝这种情况。 

另一个重要的情况是目标过于严格：```
6.00 7.00 8.00 9.00
5.00
```正确的输出是：```
impossible
```即使最后的解决方案非常小，它也会被视为最佳时间而被丢弃。 其余值为 7、8 和 9，平均值为 8.00。 任何可能的第五个结果都不可能使最终得分降低。 仅检查包含第五次的情况的解决方案将错过该下限。 

## 方法

 一种简单的方法是为第五次求解尝试不同的值，将每个值插入到五次中，对它们进行排序，删除最小和最大，然后计算平均值。 这是有效的，因为它直接遵循评分规则。 

问题是没有一小部分候选者进行第五次测试。 答案可以是 1.00 到 20.00 之间的任意值，保留两位小数，共有 1901 种可能性。 尽管在这个特定问题中该范围很小，但该方法隐藏了实际结构并且更容易出错，因为边界值决定了是否删除第五个求解。 

有用的观察是，现有四个值中只有第五个值的位置很重要。 将四个已知时间排序为：```
a <= b <= c <= d
```如果第五次大于所有四次，则将其丢弃。 分数变为：```
(a + b + c) / 3
```这是第五次无限增长时可能达到的最佳分数。 如果这已经满足目标，那么答案是`infinite`。 

如果第五次小于所有四次，则将其丢弃。 分数变为：```
(b + c + d) / 3
```这是克莱尔最后选择一个很小的时间所能强迫自己陷入的最糟糕的情况。 即使这个分数高于目标，也不存在答案。 

唯一剩下的情况是第五时间位于最小和最大已知时间之间。 删除的值始终是四个已知时间中的当前最小值和最大值，剩下：```
(b + c + x) / 3
```其中 x 是第五次。 解决这个不等式直接给出最大可接受值：```
x <= 3 * target - b - c
```暴力破解之所以有效，是因为可以针对每个可能的答案模拟评分规则，但它忽略了分数在有效区间内线性变化的情况。 对第五个解的三个可能位置的观察将问题简化为常数时间算术。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(1901) | O(1) | O(1) | 已接受但没有必要 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对四个已知求解时间进行排序。 打电话给他们`a`,`b`,`c`， 和`d`从最小到最大。 只有这四个值影响最后求解的可能范围。 
2. 当第五个解非常大时，检查结果是否已经有效。 第五个解决方案作为最差分数消失，留下`a`,`b`， 和`c`。 如果他们的平均值最多是目标，则打印`infinite`。 
3. 检查当第五次求解极小时，结果是否仍然无效。 第五个解决方案作为最佳成绩消失，留下`b`,`c`， 和`d`。 如果它们的平均值大于目标，则打印`impossible`。 
4. 否则，答案必须在最小和最大已知时间之间的区间内。 分数是`(b + c + x) / 3`，所以解不等式得到`x = 3 * target - b - c`。 
5. 打印该值，精确到小数点后两位。 

为什么它有效：

 第五个解决方案只能以三种方式影响分数。 如果超出了已知次数的范围，则将其丢弃，并且分数固定。 这两个极端的情况告诉我们是否所有可能的值都有效，或者是否没有一个有效。 如果两个极端都不适用，则第五个解是中间三个值的一部分，最终得分随之线性增加。 求解线性不等式给出精确的最大允许值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    times = list(map(float, input().split()))
    target = float(input())

    times.sort()
    a, b, c, d = times

    if (a + b + c) / 3 <= target + 1e-9:
        print("infinite")
        return

    if (b + c + d) / 3 > target + 1e-9:
        print("impossible")
        return

    ans = 3 * target - b - c
    print(f"{ans:.2f}")

if __name__ == "__main__":
    solve()
```该程序首先对四个已知时间进行排序，因为公式仅取决于它们的顺序。 变量`a`,`b`,`c`， 和`d`代表最小到最大的时间。 

第一个条件检查最终求解是最慢求解并被删除的情况。 第二个条件检查最终解决方案是最快解决方案并被删除的情况。 小 epsilon 可以防止浮点舍入改变相等比较。 

如果两次检查都失败，则第五次必须在相关间隔内。 公式`3 * target - b - c`来自重新排列平均条件。 Python 浮点值就足够了，因为输入精度仅为小数点后两位，并且最终输出四舍五入到小数点后两位。 

## 工作示例

 对于第一个样本：```
6.38 7.20 6.95 8.11
7.53
```排序后，值为 6.38、6.95、7.20、8.11。 

| 步骤| 一个 | 乙| c | d | 结果 |
 | --- | --- | --- | --- | --- | --- |
 | 排序值 | 6.38 | 6.95 | 6.95 7.20 | 7.20 8.11 | |
 | 无限检查| | | | | (6.38 + 6.95 + 7.20) / 3 = 6.84 |
 | 比较 | | | | | 6.84 <= 7.53 |

 即使最后的求解任意糟糕，平均值也已经低于目标，所以答案是`infinite`。 

对于第二个样本：```
6.38 7.20 6.95 8.11
6.99
```排序后的值是相同的。 

| 步骤| 一个 | 乙| c | d | 结果 |
 | --- | --- | --- | --- | --- | --- |
 | 无限检查| 6.38 | 6.95 | 6.95 7.20 | 7.20 8.11 | 6.84 <= 6.99 |
 | 比较 | | | | | 无限案例成功|

 输出又是`infinite`根据计算。 对于提供的目标为 6.99 的第二个样本，阈值在有效范围内，并且公式给出了最大第五解：```
3 * 6.99 - 6.95 - 7.20 = 6.82
```第五个解可以是 6.82，同时将中间三个平均值精确地保持在目标位置。

import sys
import io

def run(inp: str) -> str:

 ## 边缘情况

 通过检查最小的三个已知解来处理无限情况。 为了：```
6.00 7.00 8.00 9.00
8.00
```该算法对值进行排序并计算`(6 + 7 + 8) / 3 = 7.00`。 由于这已经低于目标，任何第五次都是可以接受的，包括远大于 9.00 的值。 

通过检查最大的三个已知解来处理不可能的情况。 为了：```
6.00 7.00 8.00 9.00
5.00
```当第五个解决方案被视为最佳时间时，可能出现的最小最终分数出现。 剩余的平均值为`(7 + 8 + 9) / 3 = 8.00`，高于 5.00。 该算法正确地拒绝了这种情况。 

有限和无限答案之间的界限也很重要。 为了：```
6.00 7.00 8.00 9.00
7.00
```无限检查之所以成功，正是因为`(6 + 7 + 8) / 3 = 7.00`。 不处理相等性的比较将错误地产生有限的答案。 

有限情况是：```
6.00 7.00 8.00 9.00
7.50
```无限检查失败是因为 7.00 不是问题，不可能检查失败是因为`(7 + 8 + 9) / 3 = 8.00`太高了。 公式给出：```
3 * 7.50 - 7.00 - 8.00 = 7.50
```因此，最终解数 7.50 正是使平均值保持在目标值的最大值。
