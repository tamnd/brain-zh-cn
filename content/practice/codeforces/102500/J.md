 ## 解决方案
 ## 问题理解

 我们有一系列评论分数。 尼克被允许花时间创建虚假帐户，其中每个帐户都可以在任一方向上将任何选定的分数更改为 1，并且他还可以删除评论。 最终剩余序列的每个分数必须非零，并且相邻分数具有相反的符号。 

如果尼克创造`f`虚假账户，分数绝对值小于`f`可以转为正值，也可以转为负值。 这样的分数就像一个通配符。 所有其他非零分数都保留其原始符号。 任务是选择要创建多少个帐户以及要删除多少条评论，以便最大限度地减少总时间。 

数组长度可以达到`5 * 10^5`，因此检查所有可能的帐户数量并重建整个序列会太慢。 我们需要几乎线性地处理账户数量增加带来的变化。 分数可以大到`10^9`，但仅限于分数成为通配符的时刻，因此巨大的数字范围本身不是问题。 

一些边缘情况很容易被忽略。 如果没有虚假账户，零分就无法留在序列中。 例如：```
1 5 7
0
```如果帐户为零，则必须删除评论，成本高昂`7`。 一个账户就可以使用，成本`5`，所以答案是`5`。 将零视为正常固定符号的解决方案会给出错误的结果。 

另一个陷阱是连续的等号可能需要多次删除。 例如：```
3 1 100
1 1 1
```不创建帐户需要删除除一条评论之外的所有三条评论，这会产生费用`200`。 创建一个帐户使所有价值都变得灵活、成本核算`1`。 仅计算相邻坏对的解决方案可能会误解所需的删除数量。 

## 方法

 直接的方法是尝试所有可能数量的虚假帐户。 对于每个值`f`，我们对每个分数进行分类，计算可以保留的最长交替子序列，并为删除的评论付费。 这是正确的，因为它明确地检查每个可能的策略。 然而，可以有`O(10^9)`可能的帐户计数，甚至将我们限制为有意义的值仍然剩下`O(n)`重建阵列成本的可能性`O(n)`。 最坏的情况变成`O(n^2)`操作，这是不可能的`n = 5 * 10^5`。 

关键的观察是分数仅改变其行为一次。 有价值的分数`x`当账户数量大于`|x|`。 在这些时刻之间，灵活注释集是不变的，因此只需要在那些时刻检查答案`n + 1`有趣的账户计数。 

对于固定数量的帐户，只有非通配符注释很重要。 考虑按原始顺序排列的两个连续的非通配符注释。 让它有`k`它们之间的通配符注释。 当符号无法通过该间隙交替时，它们就会产生冲突。 当等号具有偶数大小的间隙或相反符号具有奇数大小的间隙时，就会发生这种情况。 每一个此类冲突都需要删除一次。 

当注释成为通配符时，它就会从固定符号列表中消失。 只有相邻的两个固定评论受到影响，因此可以在常数时间内更新冲突数量。 双向链表可以让我们有效地删除新的灵活注释。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将每个分数分类为固定正号、固定负号或将成为通配符的事件。 非零分`s`变得灵活`|s| + 1`帐户，而零变得灵活`1`帐户。 
2. 从零虚假账户开始。 所有非零分数都保存在固定符号的链接列表中。 零分各贡献一项强制删除。 计算不良相邻固定对的初始数量。 
3. 按发生事件的账户数对所有通配符事件进行排序。 只需要测试这些帐户计数。 
4. 当处理一个事件时，从固定标志链表中删除该位置。 在删除它之前，减去涉及其前一个和下一个固定邻居的冲突。 删除后，如果这两个邻居仍然存在，则添加新的冲突。 
5. 处理特定帐户计数的所有事件后`f`，当前所需报告的数量已知。 总成本为：```
f * c + removals * r
```更新最低答案。 

为什么有效：对于固定数量的帐户，每个灵活的评论始终可以分配其邻居所需的符号。 唯一不可避免的问题是连续的固定注释之间的问题，其符号和距离奇偶性使得交替变得不可能。 为每个此类冲突删除一条评论就足够了，也是必要的。 增加帐户数量只会从减少的表示中删除固定评论，因此在每次删除后维护冲突计数可以保留确切的最小报告数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, c, r = map(int, input().split())
    s = list(map(int, input().split()))

    sign = [0] * n
    events = {}

    zero = 0
    for i, x in enumerate(s):
        if x == 0:
            zero += 1
            t = 1
        else:
            sign[i] = 1 if x > 0 else -1
            t = abs(x) + 1
        events.setdefault(t, []).append(i)

    prev = [-1] * n
    nxt = [-1] * n

    last = -1
    for i in range(n):
        if sign[i]:
            if last != -1:
                nxt[last] = i
                prev[i] = last
            last = i

    def bad(a, b):
        if a == -1 or b == -1:
            return 0
        gap = b - a - 1
        return 1 if ((sign[a] == sign[b]) == (gap % 2 == 0)) else 0

    removals = zero
    cur = -1
    for i in range(n):
        if sign[i]:
            if cur != -1:
                removals += bad(cur, i)
            cur = i

    ans = removals * r

    for f in sorted(events):
        for i in events[f]:
            if sign[i] == 0:
                removals -= 1
                continue

            a = prev[i]
            b = nxt[i]

            removals -= bad(a, i)
            removals -= bad(i, b)

            if a != -1:
                nxt[a] = b
            if b != -1:
                prev[b] = a

            removals += bad(a, b)

            sign[i] = 0

        ans = min(ans, f * c + removals * r)

    print(ans)

if __name__ == "__main__":
    solve()
```链接列表仅包含仍被迫具有其原始符号的评论。 当注释成为通配符时，它不再影响冲突，因为以后总是可以为其分配所需的符号。 

这`bad`功能是解决方案的核心。 两个固定注释之间的距离决定了通配符间隙是否翻转所需的奇偶校验。 由于链表中的相邻节点之间没有固定的注释，因此它们的索引差直接给出了它们之间的通配符数量。 

Python整数已经支持任意精度，因此涉及成本高达`10^9`和`5 * 10^5`评论是安全的。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) | O(n log n) | 对事件位置进行排序占主导地位； 所有链表更新都是线性的 |
 | 空间| O(n) | 数组和事件存储各自最多包含`n`条目 |

 该解决方案对每个评论进行固定次数的处理。 排序步骤是可以接受的`5 * 10^5`事件。

            zero += 1
            t = 1

    nxt = [-1] * n
    last = -1
    for i in range(n):
        if sign[i]:
            if last != -1:
                nxt[last] = i
                prev[i] = last
            last = i

    def bad(a, b):
        if a == -1 or b == -1:
            return 0
        return int(((sign[a] == sign[b]) == ((b - a - 1) % 2 == 0)))

    rem = zero
    last = -1
    for i in range(n):
        if sign[i]:
            if last != -1:
                rem += bad(last, i)
            last = i

    ans = rem * r
    for f in sorted(events):
        for i in events[f]:
            if sign[i] == 0:

                    prev[b] = a

                sign[i] = 0

    return str(ans)

 ## 边缘情况

 单个零注释演示了对零帐户中不可用分数的特殊处理：```
1 5 7
0
```该算法从一个所需的删除开始。 按账户计数`1`，零变成通配符，因此移除计数减少到零，答案变成`5`。 

一串等号演示了为什么必须通过链表来计算冲突，而不是仅查看原始数组中的对：```
3 1 100
1 1 1
```初始链表有两个坏的相邻对，因此需要两次删除。 一个账号后，每条评论都是灵活的，链接列表变空，不需要报告。 该算法检查此状态并返回`1`。
