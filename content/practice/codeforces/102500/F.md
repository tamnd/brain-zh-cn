 ## 解决方案
 ## 问题理解

 我们有`n`人们。 每个人都由一组数字来描述。 如果两个人的描述中都出现一个数字，则两个人可以直接连接。 所需的输出不是可能连接的整个图，而是包含确切内容的证明`n - 1`如此直接的联系。 这些联系必须使每个人都可以与其他人联系。 

这相当于在图中找到一棵生成树，其中人是顶点，共享数字创建边。 困难在于，显式构建所有边可能成本太高，因为许多人可以共享相同的数字。 

人数可达到`2 * 10^5`，并且所有人的描述总数也至多`2 * 10^5`。 这意味着算法应该仅处理每个给定数字少量次。 在最坏的情况下，构建每一对具有共同价值观的人可能是二次方的。 例如，如果每个人的列表中都出现一个数字，则显式图表包含大约`n * (n - 1) / 2`边缘，即周围`2 * 10^10`什么时候`n = 2 * 10^5`，远远超出了可用的时间和内存。 

有少数情况需要护理。 如果没有人共享任何数字，则答案是不可能的，因为不存在连接不同组的边缘。 

例如：```
2
1 5
1 6
```正确的输出是：```
impossible
```假设每一对人都可以以某种方式连接的粗心实现可能会输出无效的关系。 

另一种情况是，所有人都通过一条链连接，但不直接与第一个人联系。```
3
1 1
2 1 2
1 2
```一个有效的答案是：```
1 2 1
2 3 2
```尝试将人员 1 直接连接到人员 3 是错误的，因为他们没有共享号码。 

第三种边缘情况是重复使用一个非常常见的数字。 输出必须准确包含`n - 1`关系，而不是所有可能的关系。 例如，如果每个人都有号码`7`，我们只需要一棵树`n - 1`边，不是所有可能的对。 

## 方法

 一个直接的解决方案是建立一个人员图。 对于每个数字，我们可以存储包含该数字的所有人员，然后连接该组中的每一对。 该图是正确的，因为每个生成的边都代表一个有效的共享数。 构建后，深度优先搜索或并查找结构可以找到生成树。 

问题是生成的边的数量。 如果所有数字中都出现一个数字`n`描述，单一价值创造`n * (n - 1) / 2`边缘。 对于最大输入大小，这是不可能存储或处理的。 

关键的观察是我们不需要所有可能的边缘。 我们只需要足够的边缘来连接所有人。 对于许多人共享的号码，使用该号码的链或星就足够了。 我们可以为每个号码保留一名代表，并将后来拥有该号码的每个人与该代表联系起来。 这在每次出现数字时最多创建一个有用的边。 

在处理人的时候，我们可以把数字当作连接符。 第一个看到号码的人成为该连接器的所有者。 后来使用相同连接器的每个人都可以附加到该所有者。 处理完所有数字后，生成的边仅使用有效连接形成一个图。 如果该图包含`n - 1`边并连接所有顶点，它是一棵生成树。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 最坏情况下的 O(S²)，其中 S 是描述总数 | O(S²) | 太慢了 |
 | 最佳 | O(S)| O(S)| 已接受 |

 ## 算法演练

 1. 读出每个人的号码列表。 维护一张从每个号码到第一个看到该号码的人的地图。 
2. 对于一个人的每个号码，检查是否有其他人已经介绍过该号码。 如果不是，则存储当前人作为其代表。 如果是，则使用此号码在当前人员和代表之间创建边缘。 

代表充当枢纽。 以这种方式创建的每个连接都是有效的，因为两个端点包含相同的编号。 
3. 处理完所有输入后，检查创建了多少个连接。 如果少于`n - 1`，图无法连接，所以输出`impossible`。 
4. 否则，输出所有存储的连接。 

为什么它有效：

 对于每个号码，包含该号码的所有人员都通过为该号码选择的代表进行连接。 这意味着即使我们只保留一小部分边，每个可能的原始连接组仍然保持连接。 如果最终的图有足够的边来形成生成树，则生成的连接将所有人连接起来。 如果不是，则某些群体从未分享过任何号码，因此不存在有效的证据。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    owner = {}
    ans = []

    for i in range(1, n + 1):
        data = list(map(int, input().split()))
        m = data[0]
        for x in data[1:]:
            if x in owner:
                ans.append((i, owner[x], x))
            else:
                owner[x] = i

    if len(ans) != n - 1:
        print("impossible")
    else:
        out = []
        for a, b, x in ans:
            out.append(f"{a} {b} {x}")
        print("\n".join(out))

if __name__ == "__main__":
    solve()
```字典`owner`存储与每个号码关联的第一个人。 值的第一次出现不会创建边缘，因为还没有其他人可以连接。 后来的每一次出现都恰好创建一个边缘。 

该算法依赖于这样一个事实：列出的数字总数仅为`2 * 10^5`，因此迭代所有描述一次就足够了。 Python 的字典操作预计时间恒定，从而使整个解决方案呈线性。 

最后的边缘计数检查是必要的。 上的连通图`n`顶点至少需要`n - 1`边缘，并且这种构造永远不会为同一事件创建重复的不必要的边缘。 如果计数不准确`n - 1`，生成的图不能作为所需的证明。

 ## 边缘情况

 对于孤立的组，该算法从不插入边，因为两个组中都没有出现数字。 在输入中：```
2
1 5
1 6
```字典接收两个单独的条目，`5 -> 1`和`6 -> 2`，并且答案列表保持为空。 由于少于`n - 1`边缘存在，算法输出`impossible`。 

对于链式连接，该算法并不要求每对连接的人共享一个值。 在：```
3
1 1
2 1 2
1 2
```人 2 成为桥梁。 数字`1`连接人 1 和人 2，而号码`2`连接人 2 和人 3。生成的树证明所有人都是连接的。 

对于大家共享的号码：```
5
1 7
1 7
1 7
1 7
1 7
```第一个人成为所有者`7`。 后来的每个人都为第 1 个人创建一条边，恰好给出了 4 条边。 该算法避免生成十个可能的对，同时保留连接性。
