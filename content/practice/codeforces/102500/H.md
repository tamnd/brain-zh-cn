 # 问题理解

 比赛概况是通过每整数公里的道路高度来描述的。 在两个连续的公里标记之间，道路是一条直线，因此每个路段内的坡度都是恒定的。 对于每个请求的坡度，我们需要平均坡度至少为该坡度的最长水平间隔。 

直接的解释是在路线上选择两个点，并将它们的高度差与水平距离进行比较。 困难在于端点不必是整数位置。 最佳间隔可以在一公里段的中间开始或结束。 

比赛长度可以包含100000个分段，同时可以有50个不同的成绩查询。 检查每对端点的解决方案需要大约 10^10 次比较，这远远超出了合适的范围。 即使对每个可能的对进行线性扫描也是不可能的，因此每个查询的目标必须接近 O(n)。 

一个常见的错误是只检查整数公里位置。 例如，输入```
2 1
0 30 30
2.0
```答案是`1.5`，因为从 0 公里到 1.5 公里的区间每公里坡度为 20 米，即 2% 的坡度。 仅检查顶点会错过此间隔。 

另一个陷阱是假设最佳间隔必须在一个顶点结束。 考虑```
3 1
0 10 0 0
5.0
```变换后的轮廓达到段内所需的值，因此答案可能是分数距离。 任何仅更新整数坐标答案的方法都可以返回较短的结果。 

当从未达到所需的等级时，会出现第三种边缘情况：```
2 1
0 0 0
1.0
```正确的输出是`-1`。 粗心的实现可能会输出零，因为它总是找到一对相同的位置。 

# 方法

 暴力解决方案会尝试每对可能的端点。 对于每一对，它计算平均坡度并保留满足查询的最长间隔。 对于 n 个位置，这需要 O(n^2) 检查，对于最大输入大小，这大约是 10^10 次操作。 

关键的观察结果来自于重写条件。 对于查询等级 g，定义

 f(x) = 高度(x) - (g / 100) * x

 对于两个位置 a < b，从 a 到 b 的斜度至少为 g，此时

 f(b) >= f(a)。 

问题变成了找到两点之间的最长距离，其中后面的点的值至少与前面的点一样大。 

从左到右扫描时，如果我们知道到目前为止看到的 f 的最小值及其最早出现的位置，那么每个当前位置都会给出结束于此的最佳可能间隔。 唯一剩下的问题是 f 在每公里段内是连续且线性的。 由于线段是单调的，因此无需二分查找即可直接找到线段内的最佳端点。 

暴力方法之所以有效，是因为它会检查所有可能的对。 它失败了，因为对太多。 上面的变换将问题简化为在仅遍历 n 个线性片段时保持前缀最小值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个查询 O(n^2) | O(1) | O(1) | 太慢了 |
 | 最佳 | 每个查询 O(n) | 除了输入存储之外，O(1) | 已接受 |

 # 算法演练

 1. 对于查询坡度 g，从高度剖面中减去斜率 g/100 的线。 位置 x 处的新值为`height(x) - g*x/100`。 当该变换后的值不从其左端点到右端点减小时，间隔恰好有效。 
2. 开始从左到右扫描路线。 保持迄今为止看到的最小变换值以及该最小值出现的最早位置。 这为在当前位置结束的任何间隔提供了最佳可能的起点。 
3. 对于两个整数公里之间的每个线段，确定变换后的线段到达其最大有效端点的位置。 如果段不断增加，则远端始终有效。 如果它正在减少，则当段达到当前前缀最小值时，有效部分结束。 
4. 用该端点与存储的最小位置之间的距离更新答案。 完成分段后，使用分段端点更新前缀最小值，因为未来的间隔可能从那里开始。 
5. 对每个请求的等级重复扫描并打印找到的最长长度。 如果不存在正长度区间，则打印`-1`。 

为什么它有效：

 对于任何可能的结束点 y，最佳起点是 y 之前最早出现的最小变换值。 扫描始终准确存储此信息。 在每个段内，变换后的函数是线性的，因此有效终点的集合要么是整个段，要么是它的前缀。 该算法检查最远的有效终点，这是唯一可以改进答案的终点。 由于考虑了每个可能的端点，因此不能错过最大间隔。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_query(h, g):
    n = len(h) - 1
    slope_need = g / 100.0

    def value(i):
        return h[i] - slope_need * i

    cur_min = value(0)
    min_pos = 0
    ans = 0.0

    cur = value(0)

    for i in range(n):
        nxt = value(i + 1)
        seg_slope = nxt - cur

        if seg_slope >= 0:
            end = i + 1.0
        else:
            t = (cur_min - cur) / seg_slope
            if t >= 1.0:
                end = i + 1.0
            else:
                end = i + t

        if end - min_pos > ans:
            ans = end - min_pos

        cur = nxt

        if cur < cur_min:
            cur_min = cur
            min_pos = i + 1.0

    if ans <= 1e-12:
        return "-1"
    return f"{ans:.10f}"

def main():
    n, k = map(int, input().split())
    h = list(map(int, input().split()))

    grades = []
    for _ in range(k):
        grades.append(float(input()))

    out = []
    for g in grades:
        out.append(solve_query(h, g))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```该代码独立处理每个等级，因为转换取决于所请求的斜率。 功能`solve_query`保留当前的变换值、迄今为止看到的最小变换值以及达到最小值的位置。 

表达式`seg_slope = nxt - cur`是变换线段的斜率。 当它为非负数时，线段中的每个点的值至少与线段的起点一样大，因此远端点是最佳选择。 当它为负时，线最终会低于存储的最小值，并且公式计算精确的交叉点。 

所有坐标都存储为浮点值，因为最佳端点可能位于线段内。 Python 整数安全地处理原始高度，只有转换后的计算需要浮点精度。 

# 工作示例

 对于第一个样本，查询为 2.0%。 转换后的轮廓是通过每公里减去 2 米来创建的。 

| 细分 | 当前最低仓位| 当前转换值 | 最佳终点 | 回答 |
 | --- | --- | --- | --- | --- |
 | 开始| 0 | 0 | 1 | 1 |
 | 1 到 2 | 0 | -2 | 2 | 2 |
 | 2 至 3 | 0 | -4 | 3 | 3 |
 | 剩余部分 | 0 | 最低限度保持较低| 没有改善| 3 |

 从 0 公里到 3 公里的间隔恰好具有所需的平均坡度，因此答案为 3。 

对于第二个样本，查询为 2.0%。 

| 细分 | 当前最低仓位 | 当前转换值 | 最佳终点 | 回答 |
 | --- | --- | --- | --- | --- |
 | 0 到 1 | 0 | 0 | 1 | 1 |
 | 1 到 2 | 0 | 28 | 28 1.5 | 1.5 1.5 | 1.5

 第二段在变换后是平坦的，允许有分数端点。 该算法找到长度为 1.5 的区间。

 # 边缘情况

 当最佳端点位于线段内部时，算法通过递减线段交叉公式达到最佳端点。 对于输入```
2 1
0 30 30
2.0
```变换后的值为 0、28 和 26。最小值保持在位置 0。第二段从 28 减少到 26，在 1.5 公里后与最小值相交，产生正确答案。 

当每个间隔未达到要求的等级时，前缀最小值决不允许使用正的有效距离。 为了```
2 1
0 0 0
1.0
```变换后的轮廓立即减小，并且每个可能的间隔都有负调整斜率。 存储的答案仍然为零，因此程序打印`-1`。 

当整条路线有效时，最小值保留在起点，最终终点给出答案。 为了```
2 1
0 100 200
50.0
```变换后的轮廓是平坦的，因此扫描达到 2 公里并返回全长。
