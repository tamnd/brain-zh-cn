 ## 解决方案
 ## 问题理解

 我们有一个循环列表`n`怪物类型。 在更新之前，输入`i`有概率出现`s[i]`百分比。 生成位置现在只保留`k`随机选择的类型。 所选择的类型保留自己的概率，而每个删除的类型将其概率赋予在绕圈前进时遇到的第一个选择的类型。 

任务是在对所有可能的随机选择进行平均后计算每种类型的预期最终概率`k`保留类型。 

重要的是我们不需要模拟随机池。 可能的池数为`C(n, k)`，即使对于`n = 500`。 我们需要利用循环排序的对称性并独立计算每个原始概率的贡献。 

自从`n`最多 500 个`O(n^2)`算法很容易足够快。 一个`O(n^3)`这种方法已经有大约 1.25 亿次操作，并且在 Python 中是有风险的，而涉及所有子集的任何事情都是不可能的。 

在某些情况下，不正确的解决方案常常会失败。 什么时候`k = n`，每种类型始终被选择，因此答案必须等于输入。 例如：```
3 3
10 20 70
```输出是：```
10 20 70
```意外允许相邻类型贡献的公式将在此处产生错误的答案。 

什么时候`k = 1`，只有一种类型幸存下来，并且它接收所有概率质量。 为了：```
3 1
10 20 70
```输出是：```
33.333333333333 33.333333333333 33.333333333333
```每种类型都有可能成为唯一选择的类型，无论其原始概率如何。 

圆形环绕是错误的另一个来源。 为了：```
2 1
30 70
```两个答案都是`50`。 包装后第二类型可以接收第一类型的概率，并且第一类型可以接收第二类型的概率。 

## 方法

 一种直接的方法是枚举每一个可能的集合`k`选定的类型。 对于每个集合，我们可以绕圈走一圈，将每个删除的类型分配给下一个选定的类型，然后添加生成的概率。 这是正确的，因为它完全遵循生成规则。 

问题在于组数。 即使与`n = 500`,`C(500, 250)`远远超出了可以处理的范围。 蛮力还远未达到所需的复杂性。 

关键的观察是期望允许我们区分贡献。 我们不问选定类型从哪里接收概率，而是问固定原始类型的概率去哪里。 

考虑类型`i`。 它的原始概率对类型有贡献`i + d`如果选择了该目的地并且`d`未选择之前的类型。 剩余选定类型的选择方式数量仅取决于`d`，不在实际位置上。 这为圆周围的每个距离创建了一个固定系数。 

对于一段距离`d`，距离处的类型的概率`d`在后面`i`有助于`i`是：```
C(n-d-1, k-1) / C(n, k)
```分子选择另一个`k-1`从源和目标之间未阻塞的位置选择类型。 

计算这些系数一次后，每个答案位置只是原始概率的循环加权和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(C(n,k) * n) | O(C(n,k) * n) | O(n) | 太慢了 |
 | 最佳 | O(n^2) | O(n^2) | O(n) | 已接受 |

 ## 算法演练

 1. 计算每个可能的圆形距离的系数。 对于距离`d`，存储某个类型的概率`d`当前类型后面的位置将其概率转移到当前类型。 这仅基于`n`,`k`， 和`d`，因此它可以重复用于每个答案位置。 
2. 使用浮点值计算组合。 二项式值本身可能非常大，但只需要它们的比率。 自从`n`很小，双打的帕斯卡三角形就足够了。 
3. 对于每种目的地类型`i`，迭代所有距离`d`。 添加该类型的原始概率`(i - d) mod n`乘以系数`d`。 
4. 打印得到的预期概率。 

该算法背后的不变性是每个原始概率都根据每个可能目的地的概率精确分布。 距离系数`d`精确计算目的地幸存且所有较近的幸存者都不在的事件。 由于所有可能的源贡献都是独立添加的，因此期望的线性给出了正确的预期最终概率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = list(map(float, input().split()))

    comb = [[0.0] * (n + 1) for _ in range(n + 1)]
    comb[0][0] = 1.0
    for i in range(1, n + 1):
        comb[i][0] = 1.0
        comb[i][i] = 1.0
        for j in range(1, i):
            comb[i][j] = comb[i - 1][j - 1] + comb[i - 1][j]

    total = comb[n][k]

    coef = []
    for d in range(n):
        coef.append(comb[n - d - 1][k - 1] / total)

    ans = [0.0] * n
    for i in range(n):
        cur = 0.0
        for d in range(n):
            cur += s[(i - d) % n] * coef[d]
        ans[i] = cur

    print(*ans)

if __name__ == "__main__":
    solve()
```组合表存储`C(a,b)`值为浮点数。 整数存储不合适，因为这些值变得太大，而最终计算只需要比率。 

系数循环使用`n - d - 1`而不是`n - d`。 目的地本身必须已被选择，并且靠近源的位置必须不存在。 该边界是该问题中最常见的差一错误。 

最后的双循环使用模索引，因为怪物列表是循环的。 对于目的地`i`和距离`d`，源是`(i-d) mod n`。

 ## 边缘情况

 对于`k = n`，每个怪物都生存下来。 在公式中，除了距离零之外的所有系数都变为零，因为没有足够的未选择位置来创建传输。 该算法简化为返回原始数组。 

为了`k = 1`，每个系数变为`1/n`。 恰好有一个被选中的怪物，每一个原始概率最终都属于那个被同等概率选中的怪物。 圆形结构不影响结果。 

对于环绕式情况，模索引将列表视为一个圆圈。 靠近起点的源可以对靠近终点的目的地做出贡献，并且相同的系数计算仍然适用，因为距离是循环测量的。
