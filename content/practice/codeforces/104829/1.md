 ## 解决方案
 ## 问题理解

 我们会得到篮球比赛中的总得分，其中每次成功的得分动作都会贡献 1、2 或 3 分。 实际的镜头顺序尚不清楚，只有最终的总和才重要。 任务是重建能够准确产生该总数的尽可能少的评分动作。 

所以输入是一个整数n，代表两队共同累积的总分。 输出是 n 分解中的最小项数，其中每项为 1、2 或 3。换句话说，我们试图将 n 表示为集合 {1, 2, 3} 中尽可能少的整数的总和。 

约束 0 ≤ n ≤ 1000 使其成为一个非常小的状态空间。 从 O(n²) 到 O(1) 的任何解决方案都很容易就足够了，而对所有分解进行指数或强力搜索就变得不必要了。 

最微妙的边缘情况出现在 n 值较小时。 当 n = 0 时，没有得分动作，因此答案必须为 0。当 n 为 1 或 2 时，答案与数字本身匹配，因为我们不能分别用少于 1 个或 2 个镜头来表示它们。 另一个稍微不那么简单的情况是 n = 3，其中 1 个 3 分球投篮严格优于 3 个 1 分球或 1 个 2 分球加 1 个 1 分球。 

尝试将 n 的所有组合枚举为 1、2、3 的简单方法仍然可以在限制范围内工作，但很快就会变得多余且低效。 问题的结构表明了贪婪分解，因为在最小化计数方面，高价值的镜头总是支配低价值的镜头。 

## 方法

 暴力策略将尝试探索总和为 n 的所有 1、2 和 3 序列，并跟踪有效序列中的最小长度。 这本质上是生成 n 的所有有序组合，其中部分位于 {1, 2, 3} 中。 在每一步中，我们都会分支最多三种可能性，这会导致在最坏情况下类似于 3^n 的递归。 即使进行剪枝，状态的数量也会增长得非常快，当 n 达到 1000 时，这变得不可行。 

关键的观察是我们没有被要求计算或构造序列，只是为了最小化元素的数量。 每次我们将 3 个 1 分球替换为 1 个 3 分球时，我们会减少出手次数，但不会改变总数。 同样，用 1 次 2 分球代替 2 次 1 分球也能减少计数。 这表明得分较高的击球总是更可取的。 

为了最大限度地减少术语数量，我们希望使用尽可能多的三分球，然后用两分球最佳地处理剩余部分，最后在需要时使用 1 分球。 这将问题简化为 n 除以 3 的简单贪婪除法，并仔细处理余数。 

这是可行的，因为 3 是允许的最大值，并且用较大值替换较小值的任何组合永远不会增加项数。 因此，最佳结构是采用尽可能多的 3，然后是 2，然后是 1。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数 O(3^n) | O(n) 递归堆栈 | 太慢了 |
 | 最优贪心 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 使用整数除法计算我们可以从 n 中投出多少个三分球。 这给出了最有效地减少剩余金额的高价值行动的最大数量。 
2. 计算除去所有 3 分贡献后的余数。 该余数现在在 0 到 2 的范围内，因为任何整数 mod 3 都位于该区间内。 
3.如果余数为0，则无需进行额外的射击。 仅使用三分球，分解就已经是最佳的。 
4、如果余数为1或2，则正好贡献1次额外投篮，因为1可以表示为单次1分投篮，2则可以表示为单次2分投篮。 进一步分割这些没有任何好处。 
5. 最后的答案是三分球投篮次数加上一次额外投篮（如果余数不为零）。 

为什么它有效：该算法依赖于这样一个事实：用单个较高评分动作替换任何一组较小评分动作会严格减少术语数量。 由于 3 是最大允许值，因此最大化其使用量会最小化全局被加数的数量。 一旦所有 3 都被贪婪地使用，剩余值将严格小于 3，因此如果非零，则不能通过除单个项之外的任何组合进一步改进。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())

if n == 0:
    print(0)
else:
    print((n + 2) // 3)
```该实现依赖于对 3 分球投篮次数为 n // 3 的观察。余数处理隐式编码在表达式 (n + 2) // 3 中，只要 n 不能被 3 整除，该表达式就会正确舍入。这避免了对余数的显式分支，同时仍捕获最佳结构。 

显式处理特殊情况 n = 0 以确保正确性，因为在这种情况下公式也返回 0，但条件使推理变得明确且对于扩展而言稳健。

 ### 示例 1

 输入：n = 6

 我们计算出三分球投篮次数为 6 // 3 = 2。余数为 0。 

| 步骤| n | 三分球 | 余数 | 到目前为止的答案|
 | ---| ---| ---| ---| ---|
 | 开始 | 6 | 0 | 6 | 0 |

 最终结果为2，对应两次三分球。 任何替代分解（例如 2 + 2 + 2 或 1 + 1 + 1 + 1 + 1 + 1）都会使用更多镜头，从而确认最优性。 

### 示例 2

 输入：n = 10

 我们计算 10 // 3 = 3，余数为 1。 

| 步骤| n | 三分球 | 余数 | 到目前为止的答案|
 | ---| ---| ---| ---| ---|
 | 开始 | 10 | 10 0 | 10 | 10 0 |
 | 分割后| 10 | 10 3 | 1 | 3 |
 | 余数处理 | 10 | 10 3 | 1 | 4 |

 1 的剩余部分需要额外的 1 分投篮，总共 4 次。任何用 2 和 1 的组合代替 3 分球的尝试只会增加投篮总数。

 ## 边缘情况

 对于 n = 0，算法直接返回 0，因为没有可分解的点。 公式 (n + 2) // 3 的计算结果也为 0，与预期输出匹配。 

对于 n = 1，除以 3 后得到一个余数。计算得出 (1 + 2) // 3 = 1，对应于单次 1 分投篮，这是最佳选择，因为没有更大的得分动作可以代表它。 

对于 n = 2，该公式也给出 (2 + 2) // 3 = 1。 这对应于单次 2 分投篮，这是最小分解。 

对于 n = 1000，除法得到 333 个完整的三分球，余数为 1。算法返回 334，意味着 333 个三分球加上 1 个单分球。 这符合最佳结构，因为任何用 2+1 或 1+1+1 代替 3 分球的尝试都会增加而不是减少动作次数。
