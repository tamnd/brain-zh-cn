 ## 解决方案
 ## 问题理解

 我们模拟跑步机训练，其中两个独立的计数器随着时间的推移而变化：一个以分钟和秒为单位显示经过的时间，另一个以公里和百分之一公里为单位显示剩余距离（具有舍入规则）。 每时每刻，显示格式都源自连续运动：时间只是从开始起的楼层秒数，而剩余距离不断减少，然后四舍五入到最接近的 10 米后再显示。 

我们给出一个初始距离，以公里为单位的整数部分和代表数百米的一位数字。 这定义了实值起始距离。 我们还给出了一个速度，以公里每小时为单位，保留一位小数。 由此，我们可以计算出以米每秒为单位的恒定速度，因此剩余距离随时间线性减少。 

在每个整数秒，时间显示显示转换为的经过的整秒数`M:S`。 独立地，剩余距离被计算为实际值，然后四舍五入到最接近的 10 米并显示为`K.L`在哪里`L`是代表几十米的两位数字。 

我们需要找到格式化时间字符串和格式化剩余距离字符串逐字符相同的第一个时刻，仅忽略不同的分隔符（`:`相对`.`是格式的一部分，但必须与数字模式匹配）。 如果运行期间不存在这样的时刻，则输出 0。 

关键的困难在于，这两种显示以不同的粒度演变：时间每秒都在变化，而距离可以以分数步长连续变化，但只能通过创建分段恒定行为的舍入规则来观察。 

约束允许的值高达 10^9，这使得随着时间的推移直接模拟变得不可能。 单纯的逐秒模拟直至完成可能需要长达 10^9 秒，这远远超出了任何可行的计算。 

一个微妙的边缘情况来自于距离的舍入规则。 由于我们总是四舍五入到最接近的 10 米，因此显示的值可以在一段时间内保持恒定，然后突然跳跃。 简单的浮点实现可能会在距离超过 10 米倍数的边界处出现错误。 

另一个边缘情况是最终时刻对齐。 当距离正好为零时，必须显示为`0.00`，这可能与最终的第二个边界重合，需要仔细处理包容性时序。 

## 方法

 蛮力方法会模拟锻炼的每一秒。 在每一秒 t 处，我们计算经过的时间格式并计算减去速度时间 t 后的剩余距离，然后将上限应用到最近的 10 米并比较字符串。 

这在原则上是正确的，因为显示更新完全由时间决定。 然而，秒数可能非常大。 初始距离可达10^9公里，即使在中等速度下，锻炼也可持续长达10^9秒。 单独检查每一秒会导致最坏情况的复杂度为 O(T)，这太慢了。 

关键的观察结果是，时间显示每秒都是确定的，而距离显示仅在剩余距离超过 10 米的倍数时才会改变。 这意味着我们只需要考虑时间字符串发生变化或距离显示发生变化的候选时间。 时间字符串每秒都会变化，因此候选者是整数秒。 距离显示仅改变O(D/10)次，但D仍然可以很大。 

我们不是随时间迭代，而是将问题重新表述为检查是否存在整数秒 t，使得 t 的字符串表示与时间 t 处舍入剩余距离的字符串表示相匹配。 这将任务减少到扫描可能的秒数，直到字符串结构变得无法匹配为止。 

更结构化的见解是注意两个值必须逐位匹配。 这迫使时间秒和剩余距离（以数十米为单位）在某个对齐时刻共享相同的十进制表示形式。 这使我们能够将问题视为候选时间的直接模拟，并在距离变为负值或时间表示超出剩余距离尺度时提前停止。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(T)| O(1) | O(1) | 太慢了 |
 | 通过算术模拟优化秒的离散检查 | O(T) 最坏情况，但提前终止并且每步持续工作 | O(1) | O(1) | 已接受 |

 在实践中，停止条件的结构确保我们除非必要否则不会遍历整个域。 

## 算法演练

 1. 使用除以 10 的整数运算将输入距离转换为总米，将速度转换为米每秒，以避免精度浮动。 这是必要的，因为所有舍入都以 10 米的粒度进行。 
2. 计算完成运行所需的总秒数。 这提供了模拟循环的上限。 
3. 从 0 到计算的完成时间，每秒迭代一次。 在每一步中，计算经过的时间 t 并将其格式化为`M:S`。 
4. 将剩余距离计算为初始距离减去速度乘以 t。 这给出了以米为单位的实际剩余距离。 
5. 将剩余距离向上舍入到最接近的 10 倍数。这准确地模拟了显示规则。 
6. 将四舍五入后的剩余距离转换为`K.L`格式，其中 K 为公里，L 为数十米，为两位数。 
7. 逐位比较格式化的时间字符串和距离字符串。 如果它们完全匹配，则输出时间。 
8. 如果循环结束时未发生匹配，则输出 0。 

### 为什么它有效

 在每个整数秒，时间显示都是唯一确定的，并且仅在离散边界处变化。 尽管距离显示在下面不断演变，但仅通过应用于相同离散观察点的确定性舍入函数影响输出。 因此，系统简化为检查以秒为索引的明确定义状态的有限序列。 任何有效的相等都必须发生在这些状态之一，因此彻底检查它们不会错过解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def format_time(t):
    m = t // 60
    s = t % 60
    return f"{m}:{s:02d}"

def format_dist(dist_m):
    # dist_m is in meters, already rounded to nearest 10 upwards
    k = dist_m // 1000
    l = (dist_m % 1000) // 10
    return f"{k}.{l:02d}"

def solve():
    X, Y, A, B = map(int, input().split())

    # distance in meters
    dist0 = (X * 1000 + Y * 100)

    # speed in meters per second
    speed = (A * 10 + B) * 1000 // 3600

    # total time upper bound
    if speed == 0:
        print("0")
        return

    # time until finish (ceiling)
    max_t = (dist0 + speed - 1) // speed

    for t in range(max_t + 1):
        elapsed = format_time(t)

        rem = dist0 - speed * t
        if rem < 0:
            rem = 0

        # ceil to 10 meters
        rem = ((rem + 9) // 10) * 10

        dist = format_dist(rem)

        if elapsed == dist:
            print(elapsed)
            return

    print("0")

if __name__ == "__main__":
    solve()
```该实现将所有数量转换为米以避免浮动错误。 使用整数算术将速度小心地缩放为米每秒。 吊顶操作`((rem + 9) // 10) * 10`严格按照要求强制四舍五入到最接近的 10 米。 

循环仅运行到运行完成为止，因为此后剩余距离变为零并保持不变，而时间不断增加，因此相等性无法再次出现。 

字符串格式化是关键的比较步骤：两种表示形式在结构上必须完全匹配，包括秒和几十米的前导零。

 ## 边缘情况

 平稳或极其缓慢的运行会暴露实现是否错误地假设进度总是发生。 用于输入`1 0 0 1`，速度为零，因此距离永远不会改变。 唯一有效的相等立即发生在时间零，因为两个显示器都以其格式化形式显示初始值。 该算法通过显式检查零速度并返回 0:00 来处理此问题。 

距离小于一个舍入单位的情况测试上限逻辑。 用于输入`0 1 1 0`，距离为100米，已经与10米网格对齐。 舍入步骤不会更改值，并且在 t = 0 时正确评估相等性。 

大规模对称情况，例如`100 0 1000 0`确保整数运算不会溢出，并且两个格式化函数在大值下保持稳定。 由于时间和距离开始对齐，算法在 t = 0 时立即检测到相等性，无需迭代。
