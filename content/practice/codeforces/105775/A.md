 ## 解决方案
 ## 问题理解

 该问题涉及一个主数组以及我们随时间存储的附加数组流。 后来，我们收到查询，要求我们将主数组的子数组与所有存储的数组进行比较，但比较不是位置比较。 

如果两个数组包含完全相同的值的多集，则认为它们是等效的。 顺序并不重要，重要的是每个值出现的次数。 查询询问：给定主数组的一段，有多少先前存储的数组具有与该段完全相同的值频率分布。 

微妙之处在于，相等性是在_所有出现在任何地方的不同值_上定义的，而不仅仅是段内的值。 这意味着每个数组都可以被视为固定但未知的值域上的频率向量。 由于此问题中所有数组中的不同值的数量很小（以 100 为界），因此我们可以安全地将值压缩为索引并根据频率向量进行推理。 

输入大小很大：最多 200,000 个查询，插入的数组总长度最多 1,000,000。 这立即排除了每个查询从头开始重新计算频率或直接将每个存储的数组与每个查询进行比较的情况。 一个简单的解决方案是通过构建频率图来比较每个存储的数组与每个查询，成本大约为 O(Q × 总存储大小)，这太慢了。 

一些边缘情况很重要：

 一个存储的数组可能与另一个存储的数组具有相同的多重集，因此必须计算重复项。 查询子数组的值组成可能相同，但顺序不同。 例如，如果 A = [1,2,1] 并且存储的数组为 [2,1,1]，即使位置不同，它们也会匹配。 

另一个微妙的情况是数组可能包含从未出现在查询的子数组中的值。 例如，如果存储的数组包含在子数组中出现零次的额外值，它仍然会影响相等性，因此必须在相同的全局频率空间中一致地跟踪它。 

## 方法

 蛮力的想法很简单：对于每个存储的数组，计算一个频率图，对于每个查询计算 A[l..r] 的频率图，然后比较两个图。 如果它们完全匹配，我们就会计算它。 

这是正确的，因为相等是纯粹的多集相等。 然而，为每个存储的数组构建频率图的成本为 O(k)，比较两个图的成本为 O(σ)，其中 σ 是不同值的数量。 总共插入多达 10^6 个元素和多达 2×10^5 次查询，这会导致最坏的情况约为 10^11 次操作，这是不可行的。 

关键的观察是每个数组都可以转换为独立于排序的规范表示。 由于 σ ≤ 100，我们可以将每个数组表示为大小为 σ 的向量，其中每个坐标是特定值的频率。 如果我们有一种快速方法将该向量映射到可哈希对象中，我们就可以计算相同向量的出现次数。 

剩下的挑战是如何有效地表示频率向量，以便我们既可以将其插入到存储的数组中，又可以为 A 的任何子数组快速计算它。对于主数组，前缀频率数组解决了这个问题：对于每个值 id，我们维护一个前缀计数，因此 A[l..r] 中的频率是在 O(σ) 时间内计算的。 

现在每个存储的数组也会生成一个 σ 维向量。 如果我们将此向量编码为单个哈希（例如，使用跨维度的随机哈希或多项式滚动技术），我们可以将相同向量的计数存储在哈希映射中。 然后每个查询计算 A[l..r] 的向量，对其进行哈希处理，并检索有多少存储的数组与其匹配。 

这减少了维护频率矢量签名和计算相同签名的问题。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(Q × 总大小 × σ) | O（总大小）| 太慢了 |
 | 频率向量+哈希| O(总大小 × σ + Q × σ) | O（总大小）| 已接受 |

 ## 算法演练

 1. 将 A 上的所有不同值和所有插入的数组压缩为从 0 到 σ−1 的索引。 这是必要的，因为我们需要频率向量中的固定位置。 
2.为主数组A构建前缀频率数组，其中pref[i][c]存储压缩值c在A[1..i]中出现的次数。 这允许对每个值进行恒定时间频率查询。 
3. 维护一个哈希图，存储插入数组的每个频率向量出现的次数。 每个插入的数组都会转换为 σ 长度的频率向量，然后编码为单个哈希值。 
4. 对于段 [l, r] 上的类型 2 查询，使用前缀差异构建其频率向量：对于每个值 c，计算 pref[r][c] − pref[l−1][c]。 
5. 使用与存储数组相同的方法对该频率向量进行哈希处理，并从映射中返回其计数。 

重要的设计选择是使用全频率矢量的稳定编码。 直接元组适用于具有强大哈希支持的语言，但在竞争性编程中，每个维度的随机哈希在约束下更加稳健。 

为什么它有效：当且仅当每个值的频率匹配时，每个数组都由完全相同的规范对象表示。 前缀减法保证了分段频率的正确重建。 由于散列在插入和查询中是一致的，因此多重集的相等性变为散列的相等性，并且计数减少为字典中的频率计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import defaultdict

MOD = (1 << 64) - 1

def solve():
    n, q = map(int, input().split())
    A = list(map(int, input().split()))

    values = set(A)
    queries = []
    stored = []

    # read queries first to collect all values
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            k = int(tmp[1])
            arr = list(map(int, input().split()))
            stored.append(arr)
            values.update(arr)
            queries.append((1, arr))
        else:
            l, r = map(int, tmp[1:])
            queries.append((2, l, r))

    # compress values
    comp = {v: i for i, v in enumerate(values)}
    sigma = len(comp)

    # prefix frequency for A
    pref = [[0] * sigma for _ in range(n + 1)]
    for i in range(1, n + 1):
        pref[i] = pref[i - 1].copy()
        pref[i][comp[A[i - 1]]] += 1

    # random-ish hashing base
    base = [91138233 + i * 972663749 for i in range(sigma)]

    def hash_vec(vec):
        h = 0
        for i, v in enumerate(vec):
            if v:
                h = (h + v * base[i]) & MOD
        return h

    freq_map = defaultdict(int)

    ptr = 0
    stored_hashes = []

    # process stored arrays in order
    for t in queries:
        if t[0] == 1:
            arr = t[1]
            vec = [0] * sigma
            for x in arr:
                vec[comp[x]] += 1
            h = hash_vec(vec)
            freq_map[h] += 1
        else:
            l, r = t[1], t[2]
            vec = [0] * sigma
            for i in range(sigma):
                vec[i] = pref[r][i] - pref[l - 1][i]
            h = hash_vec(vec)
            print(freq_map[h])

if __name__ == "__main__":
    solve()
```该代码首先压缩值，以便频率向量紧凑且可索引。 这避免了直接处理大整数键。 

为主数组构建前缀数组，以便每个查询可以在 σ（最多为 100）的线性时间内重建频率向量。 

每个存储的数组都被转换为其频率向量，然后散列为单个整数。 该散列成为字典中的键，计算出现了多少相同的向量。 

每个查询都会根据前缀差异重建相同类型的向量并应用相同的哈希，从而允许在字典中进行恒定时间查找。 

最微妙的部分是哈希的一致性：存储数组和查询子数组都必须经过相同的编码，否则冲突会破坏正确性。 使用固定的每维度权重可确保确定性映射。

 ## 边缘情况

 一种边缘情况是主数组中的所有元素都相同。 例如，A = [7,7,7,7]。 任何子数组频率向量都会折叠为一维计数，并且许多存储的数组可能匹配。 该算法可以处理此问题，因为前缀减法仍然会产生正确的计数，并且散列仅取决于该单个坐标。 

另一种情况是，存储的数组包含从未出现在 A 中的值。例如，如果 A = [1,2,3] 并且存储的数组包含 999，则其频率向量在维度中具有非零坐标，该维度在所有查询中始终保持为零。 这保证了它的哈希永远不会匹配任何查询向量。 

最后一个微妙的情况是重复相同的存储数组。 由于我们将计数存储在哈希图中，多次插入相同的频率向量会增加其频率，因此查询可以正确计算所有重复项。
