 ## 解决方案
 ## 问题理解

 我们有一系列课程作业，其截止日期已经排序。 

任务`i`必须在绝对时间内完全完成`a[i]`。 最初每个作业都有`0%`进步。 

有`m`可用的培训选项。 选项`j`恰好属于一个作业`e[j]`。 如果我们花`t[j]`该选项的小时数、作业的完成百分比`e[j]`增加了`p[j]`。 每个选项最多可以使用一次。 

这些选项按照我们选择的顺序依次执行。 时间在全球范围内累积。 执行多个选项后，总耗用时间是它们的持续时间之和。 

对于每一个作业`i`，当时间到达截止日期时`a[i]`，从属于分配的选项中获得的总百分比`i`必须至少是`100`。 

我们必须构造一个有效的不同选项序列，或者确定不存在这样的序列。 

最重要的观察是截止日期附加在时间前缀上。 截止日期时`a[i]`到达，每项任务`1..i`必须已经达到至少`100%`，因为他们的截止日期不晚于`a[i]`。 

约束是解决方案的驱动力。 虽然`n`和`m`每个都可以大到`10^5`，总和`n+m`所有测试用例仅`2·10^5`。 这立即排除了任何指数级的情况，也排除了在全球所有选项上运行一个大背包的情况。 我们需要一些接近线性或`O(m · constant)`每个测试用例。 

一个关键的隐藏约束是每个百分比收益最多是`100`。 这意味着每个作业只关心来自的进度值`0`到`100`，这表明小背包状态。 

一些边缘情况很容易被错误处理。 

考虑一项带有选项的作业：```
deadline = 10

(t=10,p=100)
(t=1,p=60)
(t=1,p=40)
```使用单一 100% 选项可行，需要 10 小时。 使用其他两个选项也同样有效，只需 2 小时。 如果我们只检查可行性，两者似乎都是有效的。 然而，对于较晚的截止日期，总时间越短越好。 该解决方案必须最大限度地减少每项任务所消耗的时间。 

另一个陷阱是进展过快。```
deadline = 5

(t=2,p=70)
(t=2,p=70)
```进度变为 140%。 这是完全合法的。 仅存储精确总和而忘记将值限制在 100 以上的 DP 将错过此解决方案。 

第三个陷阱是作业只能通过时间进行交互。```
assignment 1 deadline = 5
assignment 2 deadline = 6
```即使作业 2 最终能够完成，作业 1 也可能会消耗太多时间，并且在截止日期之前没有留下任何空间。 在所有选定的作业选项上花费的累计时间`1..i`绝不能超过`a[i]`。 

## 方法

 蛮力方法将检查选项子集并尝试安排它们。 即使对于一项任务，也可能有数千种选择，使得`2^m`完全不可能。 

下一个想法是独立处理作业。 对于固定作业，我们需要其选项的子集，其总进度至少达到`100`，而总持续时间尽可能小。 

这突然就像一个背包问题。 

每个选项都有助于：```
weight = duration t
value = progress p
```我们希望至少达到价值`100`同时最大限度地减少重量。 

通常背包会太贵，因为持续时间可能长达`10^9`。 关键的观察结果是，进展是有限的`100`。 我们不是随时间进行 DP，而是随进度进行 DP。 

对于一项作业，令```
dp[x] = minimum time needed to obtain exactly x progress
```其中以上所有值`100`被夹到`100`。 

因为进步永远不会超过`100`，状态空间只有`101`。 

计算出一项任务可实现的最短时间后，我们将其添加到之前任务所花费的累积时间中。 如果累计时间超过该作业的截止日期，则不存在时间表。 

剩下的挑战是重建。 我们必须输出实际的期权指数。 在运行背包时，我们存储父信息并重建哪些选项形成了最佳子集。 

美妙之处在于，除了对总运行时间的贡献之外，作业是独立的。 一旦我们知道了每项作业所需的最短持续时间，使用任何较慢的方法只会使截止日期更难满足。 因此，每个分配的最优局部选择也是全局最优选择。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^m) | O(2^m) | O(米) | 太慢了 |
 | 最佳| O(米·100) | O(m + 100) | 已接受 |

 ## 算法演练

 1. 按所属任务对所有选项进行分组。 
2. 处理来自`1`到`n`按截止日期顺序。 
3. 对于当前作业，在进度上运行 0/1 背包。 

让`dp[s]`是达到进度所需的最短总持续时间`s`，其中所有进度值都大于`100`存储为状态`100`。 
4.初始化：```
dp[0] = 0
dp[1..100] = INF
```5. 逐一迭代此作业的选项。 

对于每个选项`(t, p)`，向后更新DP，就像标准的0/1背包一样。 
6.每当我们转变时```
old_state -> new_state
```并获得更好的持续时间，记录家长信息。 这稍后允许重建所选选项。 
7. 处理完所有选项后，检查`dp[100]`。 

如果仍然是无穷大，则不可能达到 100% 完成度，所以答案是`-1`。 
8. 通过跟踪状态中存储的父指针来重建所选选项索引`100`。 
9.添加最短持续时间`dp[100]`到之前作业所花费的累计时间。 
10. 如果累计时间超过截止时间`a[i]`， 输出`-1`。 

这意味着以最快的方式完成任务`1..i`错过了最后期限。 
11.否则将重构的选项索引附加到全局答案序列。 
12. 继续下一个作业。 
13. 成功处理所有分配后，输出收集的选项索引。 

### 为什么它有效

 对于固定分配，DP 计算进度至少达到的所有子集的最小总持续时间`100`。 状态空间包含每个可能的上限进度值`0`到`100`，因此没有可行的子集被忽略。 

假设一项作业可以按时完成`X`，DP 返回`Y > X`。 然后子集实现`X`将对应于有效的 DP 转换序列，与最小存储值的最优性相矛盾。 这样DP就真正找到了最短持续时间。 

作业不会争夺选项，因为每个选项都属于一个作业。 作业之间唯一的相互作用是累积的运行时间。 将某些作业的最短工期完成计划替换为较慢的完成计划永远无法帮助满足最后期限。 因此，如果作业的所有最短持续时间的总和`1..i`已经超过最后期限`a[i]`，不存在有效的时间表。 相反，如果最小持续时间的每个前缀都满足其截止日期，则通过分配执行所选子集分配会产生有效的调度。 

这证明了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        by_task = [[] for _ in range(n)]

        for idx in range(1, m + 1):
            e, tt, p = map(int, input().split())
            by_task[e - 1].append((tt, p, idx))

        total_time = 0
        answer = []
        possible = True

        for task in range(n):
            opts = by_task[task]

            k = len(opts)

            dp = [INF] * 101
            dp[0] = 0

            parent_state = [[-1] * 101 for _ in range(k + 1)]
            used_option = [[-1] * 101 for _ in range(k + 1)]

            for i in range(k):
                tt, p, idx = opts[i]

                ndp = dp[:]

                for s in range(101):
                    if dp[s] == INF:
                        continue

                    ns = min(100, s + p)
                    cand = dp[s] + tt

                    if cand < ndp[ns]:
                        ndp[ns] = cand
                        parent_state[i + 1][ns] = s
                        used_option[i + 1][ns] = i

                for s in range(101):
                    if ndp[s] == dp[s]:
                        if parent_state[i + 1][s] == -1:
                            parent_state[i + 1][s] = s

                dp = ndp

            best = dp[100]

            if best == INF:
                possible = False
                break

            total_time += best

            if total_time > a[task]:
                possible = False
                break

            chosen = []

            state = 100

            for i in range(k, 0, -1):
                if parent_state[i][state] == -1:
                    state = state
                    continue

                prev = parent_state[i][state]

                if used_option[i][state] != -1:
                    opt_index = used_option[i][state]
                    chosen.append(opts[opt_index][2])

                state = prev

            chosen.reverse()
            answer.extend(chosen)

        if not possible:
            out.append("-1")
        else:
            out.append(str(len(answer)))
            out.append(" ".join(map(str, answer)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```DP 尺寸仅为`101`，这是快速求解的关键观察结果。 

重建数组的索引为`(processed_options, progress_state)`。 当转换改善状态时，我们会记住之前的进度以及创建转换的选项。 

进度值大于`100`立即被夹紧到`100`。 缺少这个细节是错误答案的常见来源，因为许多有效的解决方案超出了`100%`。 

截止日期检查是在添加当前作业的最短持续时间后执行的。 此时，我们已经计算了分配前缀的最小可能累积时间。 即使超过了最后期限，也没有其他选择可以修复它。

 ## 边缘情况

 ### 进度超过100%

 输入：```
1
1 2
10
1 1 70
1 1 70
```第一个选项达到进度 70。第二个选项达到进度 140。DP 将其存储为状态 100。完成时间变为 2。如果没有钳位，状态 140 将不存在，并且可能会错过解决方案。 

### 作业已完成，但错过了截止日期

 输入：```
1
1 2
3
1 2 60
1 2 60
```达到 100% 的唯一方法需要 4 小时。 DP 正确找到持续时间 4。将其添加到前缀总数后，我们得到：```
4 > 3
```所以算法返回`-1`。 

### 达到 100% 的多种方法

 输入：```
1
1 3
10
1 10 100
1 1 60
1 1 40
```存在两种解决方案。```
10 hours -> 100%
2 hours -> 100%
```DP 存储每个进度状态的最小持续时间，因此状态 100 以值 2 结束。重建遵循相应的父指针并输出更快的子集。 

### 缺少完成一项作业

 输入：```
1
2 1
5 10
1 1 100
```作业1可以完成。 作业 2 根本没有选项。 

它的DP离开`dp[100] = INF`，所以算法立即输出`-1`，这是正确的，因为每个作业都必须至少达到 100%。
