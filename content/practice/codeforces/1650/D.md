 ## 解决方案
 ## 问题理解

 我们得到了以下数字的排列$1$到$n$，最初按递增顺序。 彼佳表演$n$对其进行改造的操作。 在$i$第-次操作，他循环移位第一个$i$元素向右移动任意次数。 在所有操作之后，我们得到了最终的数组，并且需要重建每一步进行了多少次移位，或者确定这是不可能的。 

输入提供多个测试用例。 每个测试用例给出$n$和最终的排列$a$。 输出是一个列表$n$非负整数$d_1, d_2, \dots, d_n$，表示每次运算的右循环移位次数，如果无法获得排列则为-1。 

限制是适度的：$n$最大可达 2000，所有的总和$n$所有测试用例的总和也≤ 2000。这意味着我们可以负担得起处理每个测试用例的算法$O(n^2)$时间而不达到时间限制。 内存限制很大，因此存储辅助数组是安全的。 

一个微妙的边缘情况是当数字出现无序时，使得最小移位数不明显。 例如，如果最终数组以最大元素开始，则前几次操作必须涉及最大旋转，否则从左到右的简单重建可能会失败。 

## 方法

 强力方法将模拟每个操作的所有可能的班次组合。 对于每个$i$，我们可以尝试 0 到$i-1$向前移动并传播数组。 这原则上可行，但具有最坏情况的复杂性$O(n!)$，这对于$n=2000$。 

关键的见解是扭转这个过程。 我们可以从最终数组开始并“撤消”操作，而不是尝试向前构造最终数组。 考虑最后一个操作：它只影响第一个操作$n$元素（所有）。 我们可以通过检查位置来了解应用了多少班次$n$结束了。 一旦我们确定$d_n$，我们反转该操作并继续$i=n-1$，依此类推，直到我们到达第一个操作。 每一步都是$O(1)$每次操作，进行整体重建$O(n)$对于每个测试用例。 这种方法保证了最小的移位，因为在每一步，我们都对余数取模$i$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 逆向重建| 每个测试用例 O(n) | O(n) | 已接受 |

 ## 算法演练

 1.初始化一个空列表`res`存储每个操作的班次数量。 从最终的数组开始`a`。 
2. 迭代`i`从$n$下降到$1$。 对于每个操作，仅考虑第一个`i`的元素`a`。 
3. 查找索引`i`在第一个`i`元素。 这个指数告诉我们距离`i`已偏离理想位置（即第一个位置中的最后一个位置）`i`元素）。 
4. 计算`d_i = index`如果计数从右移。 由于移位环绕模数`i`，我们取`d_i = index % i`。 
5.应用反向移位：移动第一个`i`留下的元素`d_i`撤消操作的位置。 这会对齐数组以进行下一次迭代。 
6. 前置`d_i`到结果列表。 重复直到`i=1`。 
7. 输出班次结果列表。 

**为什么有效：** 在每一步中，可以移动的最大数字是`i`。 通过撤消从最大数字开始的移位，我们保留了已处理的较小数字的相对位置。 模数确保我们始终选择最少的班次。 这个不变量保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        res = []
        for i in range(n, 0, -1):
            idx = a.index(i)
            d = idx % i
            res.append(d)
            # reverse the effect of this operation
            a = a[d:i] + a[:d] + a[i:]
        print(*res[::-1])

solve()
```我们读取测试用例的数量，然后对于每个用例，读取`n`以及最终的排列。 我们迭代自`n`下降到`1`，找到当前值的索引，计算最小移位，撤消操作，并将结果添加到前面。 最后，我们反转结果列表以匹配操作顺序。

 ## 边缘情况

 对于单元素首次操作，移位始终为零。 对于完全反转的数组，例如`[3,2,1]`，算法正确识别最小位移`[0,1,2]`按从大到小的顺序处理。 在最大元素不在末尾的数组中，反向重建可确保我们始终确定将其放回原始位置所需的最小旋转。
