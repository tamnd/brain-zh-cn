 ## 解决方案
 ## 问题理解

 我们在数轴上得到了点。 每个点都有一个坐标和权重。 我们想要准确地选择$2n$这些点并将它们用作端点$n$段。 

这些段必须形成完美的嵌套结构。 如果我们从最外层到最内层对段进行排序，则每个段都必须严格位于前一个段之内。 从几何角度来看，这些线段看起来就像数轴上一系列匹配的括号。 

目标不是最小化段长度。 唯一重要的是构造中使用的所有端点的权重总和。 

输入提供$m$候选点。 每个点都有一个唯一的坐标和一个原始索引。 输出必须包含尽可能小的总重量和有效的集合$n$嵌套段达到该重量。 

这些约束立即表明我们无法检查点的所有子集。 单个测试用例最多可以包含$2 \cdot 10^5$点，所有测试用例的总点数也是$2 \cdot 10^5$。 任何比粗略更糟糕的算法$O(m \log m)$每个测试用例不太可能在时间限制内舒适地适应。 二次方法被完全排除，因为$m^2$可以达到$4 \cdot 10^{10}$。 

问题的一个微妙方面是嵌套条件听起来有限制性，但一旦正确$2n$选择点后，构造嵌套段就变得微不足道了。 

考虑这个例子：```
n = 2

coordinate weight
0          1
10         1
20         100
30         100
```最佳解决方案仅在必要时才使用坐标 0 和 10 处的点以及两个昂贵的点。 由于需要正好四个端点，因此必须选择所有点。 尝试贪婪地配对附近点的粗心解决方案可能会创建交叉线段而不是嵌套线段。 

另一个容易犯的错误是假设段长度很重要。 例如：```
n = 1

coordinate weight
0          1000
1000000    1000
5          -5
10         -5
```最佳答案使用坐标 5 和 10，尽管它们的距离很小，无关紧要。 目标仅取决于权重。 

另一个陷阱是忘记允许使用负权重：```
n = 1

coordinate weight
0   -100
1   50
2   -50
```最好的一对是两个负权重点。 任何基于坐标位置而不是重量的启发式在这里都会失败。 

## 方法

 暴力解决方案会尝试每个子集$2n$点，检查这些点是否可以形成嵌套系统，并计算总权重。 这是正确的，因为它显式搜索整个解决方案空间。 

问题在于该空间的大小。 子集的数量是$$\binom{m}{2n},$$即使对于适度的值来说，这也是一个天文数字$m$。 再多的优化也无法使这一点变得可行。 

关键的观察结果是嵌套要求不会影响应选择哪些点。 

假设我们已经选择了一些集合$2n$点。 按坐标对它们进行排序：$$p_1, p_2, \dots, p_{2n}.$$现在将最左边的点与最右边的点配对，将第二个最左边的点与第二个最右边的点配对，依此类推：$$(p_1,p_{2n}), (p_2,p_{2n-1}), \dots$$这些段会自动嵌套。 每一组选择的$2n$点可以转换为有效的嵌套系统。 

这改变了整个问题。 不用担心段结构，我们只需要选择$2n$总权重最小的点。 

大小的最小权重子集$2n$显然是通过对点按权重排序并取最轻的得到的$2n$。 

选择这些点后，我们按坐标对它们进行排序，并使用上述对称配对构造嵌套对。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳|$O(m \log m)$|$O(m)$| 已接受 |

 ## 算法演练

 1. 阅读所有点及其原始索引。 
2. 按权重对点进行排序。 
3. 拿第一个$2n$点从此排序。 

这些正是$2n$总权重最小的点。 
4. 计算它们的权重之和。 
5. 对所选内容进行排序$2n$按坐标点。 
6. 将最左边的选定点与最右边的选定点配对。 
7. 将第二个最左边的选定点与第二个最右边的选定点配对。 
8. 继续直到$n$已生产对。 
9. 输出权重和以及所有构造的对。 

### 为什么它有效

 证明由两个独立的事实组成。 

首先，每个解决方案都准确使用$2n$端点。 由于目标是端点权重的总和，因此通过选择以下值可以获得最小可能的总权重$2n$所有可用点中最小的权重。 任何其他选择都会用较重的点替换一个选定的点，并且无法提高总和。 

其次，选择任意一个后$2n$点，按坐标对它们进行排序并配对对称位置会产生嵌套段。 如果排序后的点是$$p_1,p_2,\dots,p_{2n},$$那么这些对是$$(p_1,p_{2n}), (p_2,p_{2n-1}), \dots$$对于每对连续的线段，$$p_i < p_{i+1} < p_{2n-i} < p_{2n-i+1},$$这正是嵌套条件。 

由于我们实现了可能的最小端点权重并始终构建有效的嵌套系统，因此该算法是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        input()  # consume blank line

        n, m = map(int, input().split())

        points = []
        for idx in range(1, m + 1):
            x, w = map(int, input().split())
            points.append((w, x, idx))

        points.sort()  # sort by weight

        chosen = points[:2 * n]
        total_weight = sum(w for w, _, _ in chosen)

        chosen.sort(key=lambda p: p[1])  # sort by coordinate

        pairs = []
        l = 0
        r = 2 * n - 1

        while l < r:
            pairs.append((chosen[l][2], chosen[r][2]))
            l += 1
            r -= 1

        out.append(str(total_weight))
        for a, b in pairs:
            out.append(f"{a} {b}")
        out.append("")

    sys.stdout.write("\n".join(out))

solve()
```第一种排序找到全球最便宜的$2n$端点。 这是优化步骤。 

第二种排序忽略权重并按坐标排列选定的点。 一旦点按坐标顺序排列，对称配对就会自动创建嵌套。 

必须保留原始索引，因为输出需要来自输入的点编号，而不是坐标。 

每个测试用例之前的空行很容易被错误处理。 官方输入始终包含它，因此在处理每个测试用例之前读取并丢弃一行就足够了。 

Python 整数可以轻松处理权重总和，因为最大可能的大小远低于 Python 的整数限制。

 ## 边缘情况

 考虑：```
n = 1
m = 3

0  -100
1   50
2  -50
```该算法按权重排序并选择两个负点。 他们的总重量是$-150$，这显然是最优的。 坐标位置无关。 

考虑：```
n = 2
m = 4

0 1
10 2
20 3
30 4
```必须选择所有点。 按坐标排序后，算法对$(0,30)$和$(10,20)$。 第二段严格位于第一段内部，因此嵌套条件自动成立。 

考虑：```
n = 2
m = 5

0 100
1 1
2 2
3 3
4 4
```该算法丢弃权重为 100 的昂贵点并保留四个最便宜的点。 任何使用丢弃点的解决方案都会有更大的总权重。 坐标排序后，对称配对再次产生有效的嵌套结构。 

这些示例体现了两个关键思想：优化仅取决于权重，嵌套仅取决于选择点后的坐标顺序。
