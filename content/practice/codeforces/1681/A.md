 ## 解决方案
 ## 问题理解

 两个玩家各自持有一组整数。 他们玩一种回合制游戏，唯一的规则是每个新玩的数字必须严格大于前一个数字。 玩家轮流轮流，并且在每个回合中，玩家必须选择一张大于上次打出的值的剩余牌。 如果不存在这样的牌，则该玩家立即失败。 

对于每个测试用例，我们必须确定两种情况下最佳游戏的获胜者：当 Alice 开始时和 Bob 开始时。 

限制非常小。 每个玩家最多有 50 张牌，数值以 50 为界，最多有 1000 个测试用例。 这立即表明任何解决方案都可以安全地使用排序甚至简单的计数策略，而无需担心性能。 游戏状态的暴力模拟理论上也是可能的，但没有必要。 

一个微妙的问题是第一步是不受限制的。 天真的方法可能会假设“从最小的卡片开始”或“从最大的卡片开始”始终是最佳的。 一般来说，情况并非如此，因为第一个数字的选择决定了整个强制响应链。 然而，由于取值范围很小，正确的解决方案不需要深度博弈树搜索。 

另一个常见的陷阱是试图通过总是选择最小的有效下一张牌来进行贪婪模拟。 该策略可能会失败，因为它忽略了有时提前消耗一张小牌会阻止对手稍后建立更长的链条。 

## 方法

 直接的暴力解决方案将游戏视为一个状态空间，其中每个状态由最后玩的值、轮到谁以及剩余的牌来定义。 从每个状态，我们尝试所有有效的动作。 这是正确的，但很快就会呈指数增长，因为每个玩家都可以通过多种方式重新排序他们的游戏顺序。 

关键的观察是，游戏不依赖于相同值之间的顺序，唯一的约束是单调增加。 由于数值很小，真正重要的是每个玩家拥有多少张每种数值的牌。 

一旦我们对两个玩家的数组进行排序，我们就可以考虑选择一个初始值，然后贪婪地延伸最长的可能交替链。 每个玩家总是希望用仍然大于之前移动的最小可用卡来响应，因为选择更大的卡只会减少未来的选择。 

这将问题简化为检查每个可能的起始动作，序列可以延伸多远。 由于在最坏的情况下只有 100 个可能的起始值，因此这变得非常有效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力搜索 | 指数| O(n) | 太慢了|
 | 对所有开始的排序贪婪模拟 | O(t * (n + m) * 100) | O(n + m) | 已接受 |

 ## 算法演练

 我们独立解决每个测试用例。 

首先，我们对 Alice 和 Bob 的卡片进行排序。 排序确保当我们尝试扩展序列时，我们始终可以按线性扫描顺序选择下一张有效卡。 

接下来，我们尝试一切可能的第一步。 第一步有两种类型：爱丽丝开始或鲍勃开始。 对于每种情况，我们都会模拟游戏。 

在模拟过程中，我们维护一个指向每个排序列表的指针。 指针总是向前移动，永远不会后退，因为一旦使用了一张卡，它就不再被考虑。 

我们交替轮流。 在每一回合中，当前玩家都会向前移动指针，直到找到一张严格大于上次打出的值的牌。 如果不存在这样的牌，则当前玩家输，模拟结束。 

我们计算两种起始配置的结果并输出获胜者。 

字典或结构的复杂性在这里无关紧要，因为一旦确定了第一步，游戏就完全确定了。

### 为什么它有效

 在游戏的任何时刻，双方都在尽力保持未来的灵活性。 在排序数组中，选择最小的有效卡始终是最佳选择，因为它为未来的移动留下了最大可能的空间。 任何更大的选择都会严格减少可用的未来响应的数量，而不会提高继续链条的能力。 这使得贪心模拟相当于最优游戏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def simulate(a, b, start_a):
    ia = ib = 0
    last = -1
    turn_a = start_a

    while True:
        if turn_a:
            while ia < len(a) and a[ia] <= last:
                ia += 1
            if ia == len(a):
                return "Bob"
            last = a[ia]
            ia += 1
        else:
            while ib < len(b) and b[ib] <= last:
                ib += 1
            if ib == len(b):
                return "Alice"
            last = b[ib]
            ib += 1
        turn_a = not turn_a

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        m = int(input())
        b = list(map(int, input().split()))

        a.sort()
        b.sort()

        res1 = simulate(a, b, True)
        res2 = simulate(a, b, False)

        print(res1)
        print(res2)

if __name__ == "__main__":
    solve()
```该解决方案使两个数组保持排序，以便找到下一个有效的移动成为使用移动指针的线性扫描。 每个模拟在纸牌总数上以线性时间运行，因为每个指针仅向前推进。 

一个微妙的点是比较使用`<= last`，确保正确执行严格增加。 另一个重要的细节是，最后玩的值在选择一张牌后立即更新，这保证了回合转换的正确性。
