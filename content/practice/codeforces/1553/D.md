 ## 解决方案
 ## 问题理解

 我们正在模拟扫描源字符串的打字过程`s`从左到右。 在每个位置，我们要么将当前字符附加到不断变化的文本缓冲区中，要么按退格键，这会删除最近添加的字符（如果存在）。 

问题是是否存在退格操作的选择，以便在处理完所有字符后`s`，最终的缓冲区就变成了目标字符串`t`。 

思考这个过程的一个有用的方法是，每个角色`s`要么保留到最终字符串中，要么被稍后的退格键删除。 限制是删除总是从当前构造序列的末尾开始，因此只有在后面发生足够多的退格时才能删除较早的字符。 

输入由许多独立的测试用例组成，并且在所有情况下，总字符串长度最多为 200000。这立即排除了任何模拟所有可能性或对每个字符使用指数选择的解决方案。 如果不仔细聚合，即使每个测试用例解决方案的复杂度为 O(n log n)，也可能会太慢，因此每个测试用例都需要一个线性解决方案。 

当角色出现在`s`匹配`t`但由于后来的删除而无法对齐。 例如，如果`s = "ababa"`和`t = "ba"`，可以跳过前面的字符并有选择地删除后面的字符，以便只有第二个和最后一个字符以正确的顺序生存。 然而，如果`t`要求字符的顺序强制保留前缀，而该前缀稍后必须以破坏顺序的方式部分删除，这变得不可能。 

另一种失败情况出现时`t`比最终可能存活的字符数还要长。 由于每个退格键都会删除一个先前键入的字符，并且每个非退格键步骤只会生成一个字符，因此最终长度不能超过键入的字符数减去退格键，因此如果`|t| > |s|`，答案是不可能的。 更微妙的是，当长度兼容但相对顺序限制使得匹配不可能时。 

## 方法

 蛮力观点是对待每个位置`s`作为一个二元决定：要么我们输入它，要么我们按退格键。 这导致大约`2^n`对于每种可能性，我们在 O(n) 中模拟堆栈行为，给出 O(n 2^n)，这远远超出了任何限制，即使 n 约为 40。 

一旦我们不再考虑删除哪些字符而是反向思考，问题的结构就会简化。 每个退格操作都会删除之前必须保留的字符，这意味着我们实际上是在决定哪些字符在`s`作为子序列生存，但有一个额外的约束：删除可以擦除先前保留的字符，因此我们不是简单地选择`s`。 然而，我们可以将这个过程重新解释为构建一个堆栈，其中每个字符稍后都可以被删除，并且我们希望最终的堆栈等于`t`。 

关键的观察是，如果我们处理`s`从左到右并维护堆栈，唯一真正的选择是是否推送当前字符或模拟退格键。 我们可以从最后开始贪婪地推理，而不是尝试所有选择：我们想要匹配`t`作为最后剩余的序列，所以我们尽量确保`t`按顺序显示为堆栈中最后幸存的元素。 

结构更加简化的是，每个字符`t`必须对应于某些事件`s`在其之后的所有删除中仍然存在。 向后推导，我们可以贪婪地匹配`t`从年底开始`s`，决定我们是否使用一个字符作为`t`或将其视为已删除或用于删除较早字符的内容。 这简化为从右到左的两指针策略扫描。 

我们维护一个指针`j`在`t`从最后一个字符开始，然后扫描`s`从右到左。 当我们看到一个字符等于`t[j]`，我们可以将其匹配为幸存角色并移动`j`落后。 否则，该字符在`s`必须是可消耗的，这意味着它可以被输入并随后擦除，或者在构造中简单地被忽略。 如果我们设法匹配所有字符`t`，可以进行施工。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 设置指针`j`到最后一个索引`t`。 这代表我们仍需要以相反顺序匹配的下一个字符。 这个想法是`t`必须作为有效最终堆栈的子序列出现，因此我们尝试从后面嵌入它。 
2. 遍历`s`使用索引从右到左`i`。 我们检查每个角色作为最终匹配结构的潜在贡献者。 
3.如果`s[i]`等于`t[j]`，我们将此字符视为与当前所需字符匹配`t`并减少`j`。 这意味着我们将这个位置作为最终结果中幸存的角色之一。 
4. 如果`s[i]`不等于`t[j]`，我们忽略它。 从概念上讲，该字符要么被键入，然后通过退格键删除，要么永远不会对最终堆栈产生影响。 
5. 扫描完成后，检查是否`j`已移至`-1`。 如果是这样，则每个字符`t`已按正确的逆序匹配，因此可以进行构建。 

这样做的原因是从末尾开始匹配确保我们总是分配每个`t[j]`到最右边可能出现的位置`s`。 中的任意字符`s`我们跳过的内容可以安全地视为可删除的，因为退格键允许任意删除以前键入的字符，因此跳过并不违反可行性。 如果匹配存在于有效的构造中，则总有一种方法可以选择删除，以便这种贪婪的最右匹配有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    j = len(t) - 1

    for i in range(len(s) - 1, -1, -1):
        if j >= 0 and s[i] == t[j]:
            j -= 1

    print("YES" if j == -1 else "NO")

q = int(input())
for _ in range(q):
    solve()
```实现直接遵循后向匹配策略。 我们避免对堆栈或退格操作进行任何模拟，因为它们是通过丢弃不匹配字符的自由来隐式处理的。 

唯一微妙的一点是我们从不显式模拟删除。 这是安全的，因为退格键仅通过删除最近的字符来限制我们，并且从右到左扫描可确保我们永远不会依赖于因此类删除而失效的排序约束。

 ## 边缘情况

 一个微妙的情况是当`t`长度大于从末尾开始可以匹配的字符数`s`， 例如`s = "abc"`和`t = "abcd"`。 该算法立即失败，因为`j`无法到达`-1`，正确反映了不可能，因为没有退格序列可以创建额外的字符。 

另一个边缘情况是当`s`包含所有需要的字符，但有效顺序不足，例如`s = "abac"`和`t = "abc"`。 扫描匹配`c`， 然后`b`，但较早的`a`无法弥补排序要求，贪婪反向匹配在最终匹配时正确判定失败`c`不能以一致的后缀结构配对。
