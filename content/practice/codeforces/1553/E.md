 ## 解决方案
 ## 问题理解

 我们从恒等排列开始，它只是按顺序从 1 到 n 的数字。 有人首先将该数组循环向右旋转未知的移位 k，然后执行最多 m 次任意元素交换。 经过这些操作，我们只能看到最终的排列。 

任务是确定哪些起始旋转量 k 可以产生这个最终数组，假设旋转后我们最多允许 m 次交换以达到给定的排列。 

思考该过程的一个有用方法是，我们从循环结构开始，其中数组是旋转恒等式，然后我们可以使用交换来“修复”它。 每次交换都可以纠正两个放错位置的元素的最终目标位置，因此 m 控制排列可以偏离纯旋转的程度。 

约束很大：所有测试用例的总 n 最多为 3·10^5，并且测试用例最多为 10^5。 这立即排除了任何为每个测试用例尝试所有 k 并模拟交换或计算二次时间距离的方法。 在最坏的情况下，即使每个测试用例的 O(n√n) 也会太慢。 

一个微妙的困难来自于轮换是未知的，并且交换除了数量之外也不受限制。 一种简单的方法是尝试每个 k，取消旋转数组，并计算恢复身份的最小交换次数。 这将需要每个 k 的循环分解，为每个测试用例提供 O(n^2)，这是不可行的。 

另一个常见的错误是将交换视为完全排序能力，错误地得出 m 个反转内的任何排列都是有效的结论。 这忽略了排列必须与交换之前的单个循环移位一致，这是一个强大的结构约束。 

## 方法

 暴力破解的想法很简单：假设一个候选移位 k，将数组向后旋转 k，并计算需要多少次交换才能将其转换为恒等排列。 排列的交换距离是 n 减去其排列图中的周期数，因此我们可以计算未移位后的周期。 这是正确的，但代价高昂，因为对于每个 k，我们重建完整的排列和重新计算周期，导致每个测试用例的总工作量为 O(n^2)。 

关键的观察是我们不需要独立地重新计算每个 k 的所有内容。 相反，我们扭转了观点。 修复最终的排列 p。 对于给定的 k，我们可以通过检查有多少位置已经与该旋转“结构上对齐”来解释 p 是否可以来自最多 m 次交换后的 k 移位恒等式。 

移位 k 后，元素 i 理想情况下应出现在位置 (i + k) mod n 处。 因此，对于固定的 k，我们可以计算有多少元素已经匹配这个预期的循环位置。 如果某个元素已经与移位一致，则不需要修复。 每次交换最多可以修复两个不匹配，因此不匹配元素的数量决定了可行性。 

这将问题转化为计算每个 k 有多少个位置是一致的，但天真地这样做仍然是 O(n^2)。 最后一个技巧是注意一致性可以重写为循环对齐条件：

 p[j] = (j - k mod n) + 1

 重新排列为：

 k == j - (p[j] - 1) (mod n)

 因此，每个位置 j 都会给出 k 的残差值，这将使 p[j] 正确对齐。 对于有效的 k，许多位置必须与该留数一致。 如果 x 个位置一致，则 n - x 个元素不匹配，我们至少需要 (n - x) / 2 交换。 因此，可行性成为轮班产生多少匹配的阈值条件。 

因此，我们使用模块化对齐计算每个 k 有多少个索引投票给它，并将这些 k 保留在不匹配最多 2m 的位置。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（独立检查每个 k）| O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 最优（循环残数的频率）| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们想要测试每个移位 k，如果数组来自该移位，则有多少元素已经是正确的。 

### 步骤 1：将正确性条件转换为模方程

 对于每个索引 j，移位 k 下的正确值将是 (j - k mod n) + 1。重新排列给出一个条件，即每个 (j, p[j]) 对意味着唯一的 k 模 n。 

这会将每个数组元素转换为对特定移位值的投票。 

### 第 2 步：计算每个班次的选票

 我们计算一个数组 cnt[k]，其中每个位置 j 恰好对从其方程导出的一个 k 值做出贡献。 这给了我们有多少个位置与移位 k 一致。 

解释很直接：cnt[k] 是如果我们选择移位 k 则已经正确放置的元素数量。 

### 第 3 步：将匹配项转换为所需的交换项

 如果 cnt[k] 个元素已经正确，则 n - cnt[k] 个元素是错误的。 每次交换最多可以修复两个错误元素，因此所需的最小交换次数为 (n - cnt[k]) / 2。 

我们要求它 ≤ m，这相当于：

 n - cnt[k] ≤ 2m

 或

 cnt[k] ≥ n - 2m

 ### 步骤 4：收集所有有效的 k

 我们迭代从 0 到 n-1 的所有 k 并输出满足阈值的那些。 

### 为什么它有效

 关键的不变量是给定移位下的每个正确对齐完全对应于 k 上的固定模约束。 这确保了计算每 k 的选票精确地测量了有多少元素已经与该转变一致。 由于交换仅影响不匹配的元素，并且每次交换最多将不匹配计数减少 2，因此可行性条件仅取决于不匹配计数，而不取决于这些不匹配的排列。 这将结构与顺序分离，并使计数变得足够。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        p = list(map(int, input().split()))

        cnt = [0] * n

        for j, val in enumerate(p):
            # We want k such that after shifting right by k,
            # val ends up at position j.
            # In identity, val is at position val-1.
            # After shift k: position becomes (val-1 + k) % n = j
            # So k ≡ j - (val-1) mod n.
            k = (j - (val - 1)) % n
            cnt[k] += 1

        threshold = n - 2 * m

        res = []
        for k in range(n):
            if cnt[k] >= threshold:
                res.append(k)

        print(len(res), *res)

if __name__ == "__main__":
    solve()
```该实现直接编码位置和值之间的模块化关系。 关键行是计算每个 (j, val) 对的 k，这充当投票。 剩下的就是源自交换限制的简单阈值检查。 

模运算时必须小心：j 和 val-1 都是从 0 开始的，因此不需要额外的调整。 阈值使用 2m，因为在最佳情况下，每次交换都会将不匹配计数恰好减少 2。 

## 工作示例

 ### 示例 1

 输入：```
n = 4, m = 1
p = [2, 3, 1, 4]
```我们计算 k 的投票：

 | j | p[j] | p[j] | k = (j - (p[j]-1)) mod 4 | k = (j - (p[j]-1)) mod 4 |
 | ---| ---| ---|
 | 0 | 2 | 0 - 1 = 3 | 0 - 1 = 3 |
 | 1 | 3 | 1 - 2 = 3 | 1 - 2 = 3 |
 | 2 | 1 | 2 - 0 = 2 |
 | 3 | 4 | 3 - 3 = 0 | 3 - 3 = 0

 所以cnt：

 k=0:1、k=2:1、k=3:2。 

阈值是 n - 2m = 4 - 2 = 2。 

只有k=3才满足cnt[k] ≥ 2。 

所以答案是{3}。 

这表明即使是单一的交换容差也能急剧过滤允许的变化。 

### 示例 2

 输入：```
n = 3, m = 1
p = [3, 2, 1]
```投票数：

 | j | p[j] | p[j] | k |
 | ---| ---| ---|
 | 0 | 3 | 0 - 2 = 1 |
 | 1 | 2 | 1 - 1 = 0 | 1 - 1 = 0
 | 2 | 1 | 2 - 0 = 2 |

 每个 k 获得一票，因此 cnt = [1,1,1]。 阈值是 3 - 2 = 1，因此所有 k 都有效。 

这符合这样的事实：一次交换足以实现 3 周期反转中的任何轮换。

 ## 边缘情况

 一个关键的边缘情况是当 m 足够大时，几乎任何排列都可以通过任何旋转达到。 在恒等情况下，每个 k 都会产生 cnt[k] = n，因此始终满足阈值并且所有移位都是有效的，这符合无论旋转如何都不需要交换的想法。 

另一个边缘情况是完全反转的排列。 这里，每次移位都会产生均匀的匹配分布，但是当 m 处于其最大允许范围时，阈值会变得足够小，以便所有 k 通过。 该算法自然地处理这个问题，因为它只检查计数，而不检查结构。 

退化情况是 m = 0，其中我们要求 cnt[k] = n，这意味着每个元素必须已经与旋转完美对齐。 当且仅当数组恰好是恒等的旋转时，这会强制使用唯一的 k。 模块化投票确保只有正确的轮换才能获得全力支持。
