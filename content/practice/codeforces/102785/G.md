 ## 解决方案
 # 问题理解

 输入描述了二进制序列的局部规则。 该规则被写成布尔表达式，其中数字`r`表示该位`r`当前位之前的位置。 例如，`0`代表当前位，`1`代表前一位，依此类推。 该表达式可以将这些位与 AND、OR、XOR 和 NOT 组合起来。 

长度序列`n`如果定义规则的每个位置都满足表达式，则该规则有效。 如果最大参考偏移是`k`，然后从位置开始的每一位`k + 1`当当前位和前一个位时，必须使表达式计算结果为 true`k`位被代入公式中。 

任务是统计所有长度有效的二进制序列`n`。 答案需要模数`2^60`。 

的价值`n`可以达到`1000`，所以枚举所有`2^n`可能的序列是不可能的。 即使是状态包含许多先前位的动态编程解决方案，如果它线性依赖于`n`乘以指数数量的大状态。 表达式长度最多为`1000`，并且引用的偏移量仅限于以下数字`0`到`9`，这是关键的限制。 最多需要前九位来决定是否允许下一位，因此状态数由下式决定：`2^9 = 512`。 

第一个微妙的情况是表达式仅使用当前位。 例如：```
2
0
```规则说每一点都必须`x_i = 1`。 唯一有效的序列是`11`，所以答案是：```
1
```始终初始化大小状态的解决方案`2^k`和`k`至少等于 1 会错误地处理这种情况，因为没有以前的历史记录可供维护。 

另一个棘手的情况是二元运算符不遵循正常的编程语言优先级。 例如：```
2
0|1&2
```表达式计算为`(0|1)&2`，不作为`0|(1&2)`。 使用正常布尔优先级的解析器将构建错误的转换表并计算错误的序列。 

第三种边缘情况是位数仅略大于最大偏移量时：```
3
0+1
```只需要检查最后两个位置的情况。 有效序列是`000`,`001`,`010`,`011`,`100`,`101`,`110`， 和`111`除非在检查位置两个相邻位相等。 答案是`2`。 在足够的先前位存在之前开始检查的解决方案将拒绝有效的前缀。 

# 方法

 一种直接的方法是生成每个长度的二进制序列`n`，然后通过评估布尔表达式来测试每个位置。 这是正确的，因为它准确地检查了有效性的定义。 然而，序列数为`2^n`，并与`n = 1000`这远远超出了任何可能的极限。 即使检查一个序列只需要`1000`操作，最坏的情况将需要大约`1000 * 2^1000`运营。 

有用的观察是该规则仅查看固定的位窗口。 该表达式永远不能检查超过前九位和当前位的内容。 一旦我们知道了最后一个`k`位已经生成，整个较早的前缀不再影响接下来可能的位。 

这将问题转化为有限状态动态规划问题。 每个状态代表最后一个状态`k`位。 如果满足布尔表达式，则添加新位会创建到另一个状态的转换。 由于最多有`512`状态，我们可以处理所有`n`高效定位。 

暴力方法之所以有效，是因为每个完整的序列都可以独立检查，但会失败，因为可能的前缀数量呈指数增长。 有限状态视图将具有相同 future 的前缀组合在一起，允许所有等效的前缀共享一个 DP 值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 太慢了 |
 | 最佳 | O(n * 2^k)，其中 k ≤ 9 | O(2^k) | O(2^k) | 已接受 |

 # 算法演练

 1. 将布尔表达式解析成语法树。 解析器将括号视为显式分组，并在二元运算之前处理 NOT。 同一级别的所有二元运算都是从左到右计算的，因为该语句将它们定义为相同的优先级。 

语法树允许对表达式进行多次求值，而无需重复解析文本。 
2. 找出表达式中使用的最大数字。 叫它`k`。 下一位仅取决于当前位和前一位`k`位。 

如果`k`为零，每个位都可以独立检查，因为表达式仅取决于所添加的位。 
3. 为相关位的每个可能分配预先计算表达式的值。 

状态掩码包含最后一个`k`位。 当尝试一个新位时，将其与状态组合起来形成完整的赋值并对表达式求值一次。 这避免了在每次 DP 转换期间解析和评估表达式。 
4. 初始化动态编程数组。 

为了`k > 0`，每个可能的第一个块`k`位是可能的，因为在附加下一位之前无法检查规则。 每个状态都以值开始`1`。 

为了`k = 0`，从一个空状态开始，直接处理每一位。 
5. 通过尝试两个可能的新位来处理每个剩余位置。 

对于每个当前状态，附加`0`和`1`。 如果表达式的计算结果为 true，则移动到通过删除最旧的位并保留最新的位形成的新状态`k`位。 
6. 对所有最终状态求和。 

毕竟`n`位已经生成，每个剩余状态代表以该状态结束的有效完整序列。 他们的计数共同构成了答案。 

为什么它有效：

 动态编程不变量是，在处理序列的前缀之后，状态中存储的值正是以该状态表示的位模式结尾的有效前缀的数量。 具有相同状态的两个前缀具有相同的可能延续，因为该规则仅检查存储的最近位。 每个有效序列都遵循一个转换链，并且仅当满足布尔条件时才会创建每个转换，因此最终的总和仅对每个有效序列计数一次。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1 << 60

class Parser:
    def __init__(self, s):
        self.s = s
        self.i = 0

    def parse(self):
        node = self.parse_atom()
        while self.i < len(self.s) and self.s[self.i] in "&|+":
            op = self.s[self.i]
            self.i += 1
            right = self.parse_atom()
            node = (op, node, right)
        return node

    def parse_atom(self):
        c = self.s[self.i]
        if c == '-':
            self.i += 1
            return ('-', self.parse_atom())
        if c == '(':
            self.i += 1
            node = self.parse()
            self.i += 1
            return node
        self.i += 1
        return ('var', int(c))

def eval_tree(node, bits):
    t = node[0]
    if t == 'var':
        return (bits >> node[1]) & 1
    if t == '-':
        return 1 - eval_tree(node[1], bits)
    a = eval_tree(node[1], bits)
    b = eval_tree(node[2], bits)
    if t == '&':
        return a & b
    if t == '|':
        return a | b
    return a ^ b

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)
    expr = input().strip()

    k = 0
    for c in expr:
        if c.isdigit():
            k = max(k, int(c))

    tree = Parser(expr).parse()

    if k == 0:
        value = eval_tree(tree, 0)
        if value == 1:
            print(pow(2, n, MOD))
        else:
            print(0)
        return

    limit = 1 << k
    good = [[False, False] for _ in range(limit)]

    for state in range(limit):
        for bit in range(2):
            mask = state | (bit << k)
            good[state][bit] = eval_tree(tree, mask) == 1

    dp = [1] * limit
    mask_limit = limit - 1

    for _ in range(k, n):
        ndp = [0] * limit
        for state, count in enumerate(dp):
            if count:
                if good[state][0]:
                    ndp[(state >> 1)] = (ndp[state >> 1] + count) & (MOD - 1)
                if good[state][1]:
                    ndp[((state >> 1) | (1 << (k - 1)))] = (
                        ndp[(state >> 1) | (1 << (k - 1))] + count
                    ) & (MOD - 1)
        dp = ndp

    print(sum(dp) & (MOD - 1))

if __name__ == "__main__":
    solve()
```解析器构建一棵二叉树，其中每个叶子都是一个引用的位位置。 递归下降顺序符合问题的异常运算符规则：首先处理括号，NOT 绑定到以下表达式，二元运算符从左到右组合。 

预处理阶段计算是否附加`0`或者`1`每个可能的历史状态都允许。 状态掩码仅存储之前的状态`k`位。 新添加的位被放置在位置`k`暂时的，因为表达式使用相对于当前位置的偏移量。 

DP 从所有可能的初始历史开始，因为在第一个历史之前没有检查任何规则`k`位是已知的。 每次转换都会将状态移动一个位置并插入新位。 表达式检查发生在转换之前，使用旧历史记录和候选位。 

模运算使用`2^60`。 由于模数是 2 的幂，因此可以使用位掩码仅保留最低 60 位，这比一般的余数运算更快。

 # 边缘情况

 对于仅当前位表达式：```
2
0
```该算法检测到`k = 0`。 它对表达式求值一次以获得零位值。 由于只接受一个，因此每个位置都必须包含一个。 答案就变成了`2^n`仅当表达式接受两个位值时，否则它是 1 或 0，具体取决于强制序列。 

对于不寻常的运算符优先级情况：```
2
0|1&2
```解析器首先读取`0`，然后将其与`1`使用 OR，最后将结果与`2`使用“与”。 语法树表示`((0|1)&2)`，与语句相符。 正常的语言解析器会构建不同的树并产生不正确的转换。 

对于具有大偏移量的规则：```
3
0+1
```最大偏移量为 1，因此该状态有一位前一位。 第一位不经检查就被存储。 随后的每个位都会针对前一个位进行测试，并且在每次接受的转换后状态都会发生变化。 该算法不会检查不存在的较早位，因此仅计算定义条件的位置。
