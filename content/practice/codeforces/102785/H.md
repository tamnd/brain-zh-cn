 ## 解决方案
 # 问题理解

 我们需要构造一个长度的序列`k`这样每个位置都描述了它的索引在整个序列中出现的频率。 如果位置的值`i`是`x`，然后是数字`i`必须准确发生`x`所有元素中的次。 

输入给出序列长度，然后给出需要其值的索引列表。 我们不必打印整个序列，只需按相同顺序打印请求的元素即可。 如果不存在所需长度的有效序列，我们打印`0`。 

长度最多为`230`，而请求的位置数量可以达到`100000`。 这会立即排除任何构建许多候选序列或为每个查询重复扫描整个序列的情况。 我们需要在大致线性的时间内找到一个有效的序列，然后通过直接索引来回答查询。 

棘手的部分不是输出大小，而是自引用条件。 一个序列可能看起来局部有效，但全局失败，因为更改一个值会更改多个频率计数。 

考虑`k = 3`。 粗心的实施可能会尝试`[1, 2, 0]`因为它类似于有效长度四的示例。 然而，计数是：零出现一次，一出现一次，二出现一次。 所需的值将是`[1, 1, 1]`，因此该候选人无效。 

另一个常见的错误是假设每个长度都有一个解决方案。 为了`k = 1`，唯一可能的序列是`[0]`和`[1]`。 在`[0]`，零出现一次，但索引零处的值为零。 在`[1]`，零出现零次，但索引零处的值为一。 正确的输出是`0`。 

小长度是需要特殊处理的地方。 只有当有足够的空间将所需的非零频率放置在不同的索引处时，一般结构才开始工作。 

# 方法

 直接的暴力解决方案将尝试所有可能的值`k`位置并验证结果序列是否描述其自身。 由于每个元素都可能位于`0`和`k - 1`，这个搜索空间是巨大的。 即使进行修剪，最坏的情况也会呈指数级增长，并且是不可能的`k = 230`。 

有用的观察来自于查看所有值的总和。 该序列包含`k`数字，这些数字是出现的次数，因此它们的总和必须恰好等于`k`。 

让`z`是序列中零的数量。 因为索引处的值`0`告诉我们存在多少个零，我们有`a[0] = z`。 剩余的非零条目之和必须为`k - z`，它们的计数也是`k - z`。 这意味着所有剩余的非零条目精确平均`1`。 获得具有该平均值的正整数而不使每个值都等于 1 的唯一方法是让一个值等于 2，而所有其他值等于 1。 

对于足够大的`k`，我们可以使四个位置恰好非零。 令这些非零值为：`k - 4`,`2`,`1`,`1`。 

价值`k - 4`出现一次，值`2`出现一次，其值`1`出现两次。 其余`k - 4`位置为零。 因此顺序是：`a[0] = k - 4`

`a[1] = 2`

`a[2] = 1`

`a[k - 4] = 1`所有其他位置均为零。 

这适用于每个`k >= 7`， 因为`k - 4`至少是`3`，因此所有四个特殊索引都是不同的。 

剩余的有效案例足够小，可以用固定的已知答案列表来处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(k) | 太慢了 |
 | 最佳 | O(k + n) | O(k) | 已接受 |

 # 算法演练

 1.如果`k`是`4`，使用有效序列`[1, 2, 1, 0]`。 这是由于特殊索引重叠而无法应用一般构造的小情况之一。 
2.如果`k`至少是`7`，创建一个长度的数组`k`充满了零。 放`a[0]`到`k - 4`， 放`a[1]`到`2`， 放`a[2]`到`1`，并设置`a[k - 4]`到`1`。 这四个值准确地创建了定义所需的频率。 
3. 对于所有其他长度，报告不存在自描述序列。 
4. 如果创建了序列，则通过直接读取存储的值来回答每个请求的索引。 

为什么它有效：

 该结构有四个非零值。 索引零处的值为`k - 4`，所以一定有`k - 4`零。 由于其他三个非零位置包含`2`,`1`， 和`1`，正好有`k - 4`零个条目并且正好出现两次`1`, 出现一次`2`，并且出现一次`k - 4`。 存储在索引处的值`1`,`2`， 和`k - 4`正是这些频率，因此每个索引都描述了自己的出现次数。 

# Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    k = int(input())
    n = int(input())
    queries = list(map(int, input().split()))

    ans = None

    if k == 4:
        ans = [1, 2, 1, 0]
    elif k >= 7:
        ans = [0] * k
        ans[0] = k - 4
        ans[1] = 2
        ans[2] = 1
        ans[k - 4] = 1

    if ans is None:
        print(0)
        return

    print(" ".join(str(ans[x]) for x in queries))

if __name__ == "__main__":
    solve()
```程序首先判断是否存在有效序列。 仅在知道长度类别后才创建数组，这避免了不可能的情况下的不必要的工作。 

为了`k >= 7`，分配顺序很重要，因为`k - 4`必须用作索引。 条件保证该索引不同于`0`,`1`， 和`2`，因此所有分配都不会相互覆盖。 

最终输出步骤仅执行数组查找。 这是必要的，因为查询的数量远大于`k`，并且为每个请求重新计算频率将是一种浪费。 

# 工作示例

 对于第一个例子，长度是`4`并且要求的索引都是仓位。 

| 步骤| k | 构造序列 | 输出值|
 | --- | --- | --- | --- |
 | 1 | 4 | 使用特殊情况`[1,2,1,0]`| |
 | 2 | 4 |`[1,2,1,0]`|`1 2 1 0`|

 该序列包含一个零、两个一和一个二。 这些计数与索引零、一和二处存储的值匹配。 

对于第二个示例，长度为`7`使用一般结构。 

| 步骤| k | k-4 | 构造序列 | 输出值|
 | --- | --- | --- | --- | --- |
 | 1 | 7 | 3 | 从全零开始 | |
 | 2 | 7 | 3 | 放`a[0]=3`,`a[1]=2`,`a[2]=1`,`a[3]=1`| |
 | 3 | 7 | 3 |`[3,2,1,1,0,0,0]`| 读取请求的值 |

 值的计数方式如下：0 出现 3 次、1 出现两次、2 出现 1 次、3 出现 1 次。 这与构造的数组相匹配。

 # 边缘情况

 对于`k = 1`，算法到达不可能分支。 不存在有效的序列，因为单个元素不能同时等于其自身值的计数并满足零计数要求。 

为了`k = 4`，通用公式会尝试将特殊值放在索引处`0`， 因为`k - 4 = 0`。 这将覆盖构造逻辑。 显式序列`[1,2,1,0]`避免了这种重叠并完全满足定义。 

为了`k = 7`，公式给出`k - 4 = 3`, 生产`[3,2,1,1,0,0,0]`。 正好有三个零、两个一、一个二和一个三，与索引处的值匹配`0`,`1`,`2`， 和`3`。 这确认了总体施工变得安全的第一个边界。
