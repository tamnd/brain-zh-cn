 ## 问题理解

 我们有一个`N x N`房屋委员会。 有些细胞一开始就含有小精灵。 每个细胞开始时都会亮起灯，因此小魔怪无法穿过它。 随着时间的推移，历史描述了灯被关闭的单元格。 单元变暗后，它会永远保持可用状态。 小魔怪可以在侧面相邻的黑暗牢房之间移动，到达外部边界上的任何牢房意味着它可以离开城镇。 

任务是找到历史上最早的操作，此后至少有一个初始小精灵属于接触边界的暗单元的连接区域。 如果在任何操作之前这样的路径已经存在，则答案是`0`。 

板材尺寸可达`500 x 500`，这意味着最多有`250000`细胞。 历史记录还可以包含最多`250000`运营。 每次操作后重复搜索整个板的解决方案可以执行大约`250000 * 250000`细胞访问，大约是`6.25 * 10^10`操作，远远超出了极限。 我们需要一种方法，其中每个单元和每个操作仅被处理少量次。 

主要的边缘情况来自董事会的动态性质。 粗心的解决方案可能会忘记一个单元可以多次关闭。 例如：```
2 1 2
0 0
0 1
0 1
```小妖精开始于`(0,0)`，已经在边界上，所以正确答案是`0`。 仅在处理历史事件后进行检查的解决方案将错误地返回`1`。 

另一个棘手的情况是当新打开的单元连接两个先前分离的黑暗区域时。 例如：```
3 1 2
1 1
0 1
1 0
```第一次手术后，`(0,1)`是一个边界单元，小魔怪可以通过它逃脱，所以答案是`1`。 仅检查新打开的单元本身是否包含 gremlin 的解决方案将错过通过连接创建的路径。 

第三个常见错误是将对角线单元视为相连的。 例如：```
3 1 2
1 1
0 0
2 2
```两个暗单元彼此成对角线且不形成路径。 正确答案不是`1`因为对角线移动是不可能的。 

## 方法

 一种直接的方法是精确模拟该过程。 每个灯关闭后，我们可以从每个小精灵位置运行图形遍历，并检查是否可以通过暗单元到达边界单元。 这是正确的，因为它直接测试转义的定义。 

问题是成本。 在最坏的情况下可能会出现`250000`历史事件，每次广度优先搜索都可以访问`250000`细胞。 总工作量可达约`6.25 * 10^10`访问，速度太慢。 

有用的观察结果是网格中的唯一变化是将单元格添加到可用单元格集中。 一旦细胞变暗，它就不会再被阻塞。 这意味着暗细胞的连接成分只会随着时间的推移而合并。 我们不需要每次都知道确切的路径，只需要知道组件是否包含小精灵以及它是否触及边界即可。 

不相交的集合并集结构适合这种行为。 每个暗单元都表示为一个节点。 当一个小区关闭时，我们激活它并将其与每个已经活动的邻居合并。 除了每个组件的父组件之外，我们还存储两个属性：组件是否包含至少一个起始小精灵以及是否包含边框单元格。 每次合并后，如果生成的组件的两个属性都为 true，则此时可能会发生转义。 

暴力方法反复发现相同的连接区域。 DSU 方法会记住这些区域，并且仅更新受新打开的单元格影响的图表的一小部分。

 | ---| ---| ---| ---|
 | 蛮力 | O(K * N²) | O(N²) | 太慢了|
 | 最佳 | O(N² + K * α(N²)) | O(N² + K * α(N²)) | O(N²) | 已接受 |

 ## 算法演练

 1. 创建一个包含每个棋盘位置的不相交集并集结构。 最初，每个单元都处于非活动状态，因为所有灯都亮着。 为每个组件存储两个标志：是否包含初始 gremlin 以及是否触及边框。 
2. 标记 DSU 数据中的每个起始 gremlin 位置。 如果任何起始位置已经在边界上，则答案立即`0`，因为小魔怪无需等待任何灯熄灭就可以逃脱。 
3. 按顺序处理历史记录。 对于每个操作，激活指定的单元格。 如果它已经处于活动状态，因为同一房屋在历史中较早出现，则无需创建新连接。 
4. 激活新单元时，检查其四个邻居。 任何已经处于活动状态的邻居都属于同一暗区域，并且应该与新单元格的组件合并。 
5. 在所有必要的合并之后，检查包含新激活的单元的组件。 如果它同时具有小精灵和边界单元，则当前操作编号是第一个可能的逃逸时刻。 
6. 第一次出现这种情况就是答案，因为细胞只会变暗，成分只会生长。 稍后的行动无法创造更早的逃跑机会。 

工作原理：DSU 始终准确地代表所有当前暗单元的连接组件。 当某些原始 gremlin 可以到达该组件中的每个单元格时，存储的 gremlin 标志恰好为 true，并且当组件提供出口时，边界标志恰好为 true。 当且仅当其组件具有这两个属性时，小魔怪才能逃脱。 由于每个操作仅添加暗单元，因此组件具有这两种属性的第一个操作正是所需的最早时刻。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    
    size = n * n
    parent = list(range(size))
    active = [False] * size
    has_gremlin = [False] * size
    has_border = [False] * size

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        ra = find(a)
        rb = find(b)
        if ra == rb:
            return ra
        if size_rank[ra] < size_rank[rb]:
            ra, rb = rb, ra
        parent[rb] = ra
        has_gremlin[ra] |= has_gremlin[rb]
        has_border[ra] |= has_border[rb]
        if size_rank[ra] == size_rank[rb]:
            size_rank[ra] += 1
        return ra

    size_rank = [0] * size

    gremlins = []
    answer = -1

    for _ in range(m):
        x, y = map(int, input().split())
        idx = x * n + y
        gremlins.append(idx)
        has_gremlin[idx] = True
        if x == 0 or y == 0 or x == n - 1 or y == n - 1:
            answer = 0

    history = []
    for _ in range(k):
        x, y = map(int, input().split())
        history.append((x, y))

    if answer == 0:
        print(0)
        return

    directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    for step, (x, y) in enumerate(history, 1):
        idx = x * n + y

        if not active[idx]:
            active[idx] = True
            root = idx

            if x == 0 or y == 0 or x == n - 1 or y == n - 1:
                has_border[root] = True

            for dx, dy in directions:
                nx = x + dx
                ny = y + dy
                if 0 <= nx < n and 0 <= ny < n:
                    nxt = nx * n + ny
                    if active[nxt]:
                        root = union(root, nxt)

        root = find(idx)
        if has_gremlin[root] and has_border[root]:
            print(step)
            return

    print(k)

if __name__ == "__main__":
    solve()
```DSU 数组通过展平进行索引`(x, y)`进入`x * n + y`。 这避免了存储大型嵌套结构并提供对每个单元的恒定时间访问。 

这`active`数组与 DSU 状态是分开的，因为非活动单元不得参与联合。 所有单元格都存在父数组，但单元格仅在激活后成为当前图的一部分。 

这`union`操作使用逻辑或组合两个组件属性。 如果任一旧组件有一个 gremlin，则合并后的组件也有一个。 同样的道理也适用于边境接触。 操作顺序很重要：必须在检查其邻居之前激活新小区，否则将丢失通过该小区的连接。 

最终检查仅对包含已更改单元格的组件执行，因为在此操作期间所有其他组件均未更改。 使用排序联合和路径压缩使每个 DSU 操作的时间几乎恒定。

 ## 边缘情况

 第一个边缘情况是初始逃逸。 在输入中：```
2 1 2
0 0
0 1
0 1
```小妖精开始于`(0,0)`，这已经是一个边界单元了。 该算法在激活任何历史单元格之前检查这一点并返回`0`。 

第二个边缘情况是重复的历史条目。 如果同一单元被关闭多次，第二次发生时不会创建新的连接。 这`active`阵列可防止重复激活，因此 DSU 状态保持正确。 

第三种边缘情况是间接创建的连接。 在：```
3 1 2
1 1
0 1
1 0
```第一次操作后，细胞`(0,1)`被激活并直接连接到 gremlin`(1,1)`。 该组件有一个小精灵并触及边界，因此算法返回`1`。 

第四种边缘情况是对角邻接。 如果暗细胞放置在`(0,0)`和`(1,1)`，它们保留在单独的组件中，因为算法仅检查四个侧面邻居。 这符合移动规则并防止错误逃逸。
