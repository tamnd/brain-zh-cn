 ## 解决方案
 ## 问题理解

 我们分到几间宿舍，排成一排。 每个宿舍都包含已知数量的房间，并且所有宿舍中的所有房间在概念上都连接成一个长序列。 第一个宿舍首先贡献其房间，然后是第二个宿舍，依此类推，形成从 1 到房间总数的单一连续编号。 

任务是回答查询，其中每个查询给出此组合序列中的全局房间索引。 对于每个这样的索引，我们需要确定两件事：哪个宿舍包含该房间，以及该房间的本地索引在该宿舍内。 

输入的大小使得结构变得很重要。 宿舍数量和查询最多可达20万个，每个宿舍最多可有10间房间。 这立即排除了任何尝试模拟完整展平数组或线性扫描每个查询的方法。 即使每次查询扫描宿舍，在最坏的情况下也会导致 2×10⁵ × 2×10⁵ 操作，这远远超出了时间限制。 

一个微妙的边缘情况来自累积和的边界值。 例如，如果宿舍有大小`[3, 5]`，则全局索引 1 到 3 映射到宿舍 1，4 到 8 映射到宿舍 2。一个幼稚的错误是将前缀和不一致地视为开区间，从而导致差一错误，例如如果边界条件处理不仔细，则将索引 3 错误地映射到第二个宿舍。 

另一个边缘情况是处理恰好落在宿舍最后一个房间的查询。 例如，如果累计总和是`[10, 25, 37]`，然后查询`10`必须映射到第一宿舍，而不是第二宿舍。 这就是严格不平等与非严格不平等的重要性所在。 

## 方法

 暴力策略将通过遍历宿舍来独立处理每个查询，减去房间数，直到剩余的索引适合宿舍。 对于单个查询，这是 O(n)。 经过 m 次查询，这变成了 O(nm)，在最坏的情况下达到 4×10^10 次操作，这是不可行的。 

问题的结构表明了一种累积的观点。 如果我们计算宿舍大小的前缀和，每个宿舍对应数轴上的一个连续区间。 那么每个查询就变成了一个点定位问题：找到第一个大于或等于查询值的前缀和。 

这正是对单调数组的二分搜索。 由于前缀和严格递增，因此我们可以在每次查询的 O(log n) 内找到正确的宿舍。 找到宿舍索引后，减去前面的前缀和就得到了本地的房间号。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了|
 | 前缀和+二分查找 | O(m log n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算宿舍大小的前缀和，使每个位置代表该宿舍的最后一个全局索引。 这将问题转化为搜索范围而不是迭代结构。 
2.对于每个查询值`x`，对前缀和数组进行二分查找，找到最小的索引`i`这样`prefix[i] >= x`。 这标识了包含该房间的宿舍，因为`x`位于其累积区间内。 
3.一次宿舍`i`找到后，计算本地房间索引。 如果`i`是第一宿舍，答案很简单`x`。 否则，减去`prefix[i-1]`从`x`。 
4. 输出`(i + 1, local_index)`因为宿舍是1索引的。 

关键的推理步骤是，每个宿舍在数轴上占据一个连续的线段，因此定位一个房间就相当于定位哪个线段包含一个点。 

### 为什么它有效

 前缀和数组将全局编号划分为不相交的连续间隔，其中每个间隔恰好对应一个宿舍。 由于前缀和严格递增，因此每个查询值恰好落入一个区间。 二分搜索通过利用单调性找到该区间，并减去先前的边界产生区间内的正确偏移量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    prefix = []
    s = 0
    for x in a:
        s += x
        prefix.append(s)

    import bisect

    out = []
    for x in b:
        i = bisect.bisect_left(prefix, x)
        prev = prefix[i - 1] if i > 0 else 0
        out.append(f"{i + 1} {x - prev}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案一次性构建前缀和。 关键的实现细节是使用`bisect_left`，它找到不小于查询的第一个前缀和。 这可以正确处理边界值：如果查询恰好等于前缀和，它仍然映射到相应的宿舍而不是下一个。 

减法步骤小心地使用前面的前缀和，并为第一宿舍设置条件以避免负索引。 这就是许多错误解决方案失败的地方，因为要么总是减去边界情况，要么完全忘记边界情况。

 ## 边缘情况

 一种重要的边缘情况是查询完全等于前缀和。 例如，如果宿舍面积为`[4, 6]`，前缀是`[4, 10]`，查询是`4`。 二分查找返回索引`0`，本地索引变为`4 - 0 = 4`，正确映射到第一宿舍最后一个房间。 

另一个边缘情况是当查询落入最后一个宿舍时。 带前缀`[4, 10]`并查询`9`, 二分查找返回索引`1`, 之前的前缀`4`，本地索引变为`5`，正确识别第二宿舍。 

这些案例证实，将每个宿舍视为前缀边界上的闭区间，并结合`bisect_left`产生正确且稳定的分类。
