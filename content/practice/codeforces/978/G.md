 ## 解决方案
 ## 问题理解

 我们给出的时间表是$n$天和一组$m$考试，每次考试都固定在特定的某一天进行。 每项考试还都有一个准备窗口，该准备窗口从公告日后开始，到考试前一天结束，加上所需的准备天数。 

每一天都可以以一种方式使用。 Petya 要么休息，准备一场考试，要么参加考试。 准备考试不必是连续的，不同的考试可以在几天内自由穿插。 唯一的硬性限制是，每项考试都必须在其允许的时间范围内准确地获得所需的准备天数，并且在考试当天不能进行任何准备。 

输出是完整的长度表$n$，将每天分配给休息、准备特定考试或参加考试。 如果存在多个计划，则任何有效的计划都可以接受。 

关键的结构性困难在于，准备时段会在重叠的时间窗口内竞争，而考试日则永久消除了可用性。 

限制因素$n \le 100$,$m \le n$立即排除任何对时间表的指数搜索。 即使是对作业的天真回溯$n$每天有 3 个选择的日子是$3^n$，这是不可行的。 相反，我们需要一种贪婪的构造，在保持可行性的同时一天一天地分配。 

当多项考试的准备时间重叠且截止日期紧迫时，就会出现微妙的边缘情况。 例如，两项考试可能都需要在共享考试日之前进行准备，但可能没有足够的“自由”天数，除非我们仔细优先考虑哪项考试需要更早的准备。 

如果我们贪婪地分配准备而不考虑未来的可行性，就会出现另一种失败模式。 例如，如果我们在截止日期较晚的情况下安排较早的考试时间，我们稍后可能会发现无法完成紧张的考试。 

## 方法

 一个蛮力的想法是将每一天视为时间表中的一个位置，并尝试所有准备和休息作业，同时确保考试日期是固定的。 然后，每个考生的日程安排将通过计算每次考试的准备情况和检查时间窗口来验证。 这种方法原则上是正确的，但探索了一个大致大小的巨大搜索空间$3^n$，即使对于$n = 100$。 

问题的结构提出了不同的观点。 每项考试都需要一定数量的“槽位”，这些“槽位”必须放置在一个区间内$[s_i, d_i)$，不包括考试日本身。 考试日是一项强制作业，并充当硬约束，从时间表中删除单个位置。 这将问题转化为一个受约束的调度任务，我们逐渐填充可用的槽位。 

关键的观察是，我们可以按顺序处理日子并贪婪地决定作业，但我们必须始终优先考虑有可能变得不可行的考试。 在任何一天，如果有多个考试可供准备，我们应该优先考虑考试日期最接近且仍需要准备的考试。 这可以防止出现这样的情况：临近截止日期的考试没有可用的时间，而我们却把时间浪费在更灵活的考试上。 

这自然会导致具有优先级结构的贪婪过程：我们维护当前可用于准备的考试并跟踪剩余的所需准备。 我们总是将每个空闲日分配给当前有效的最紧急的未完成考试。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(3^n)$|$O(n)$| 太慢了|
 | 贪心优先|$O(nm \log m)$|$O(n + m)$| 已接受 |

 ## 算法演练

 我们从 1 点到$n$。 

1. 首先，我们记录所有考试日，以便我们知道哪些天是强制考试日。 在那些日子里，不允许做任何准备。 
2. 对于每次考试，我们都会存储其剩余的所需准备$c_i$，开始日$s_i$，及其考试日$d_i$。 
3. 我们迭代从 1 到$n$。 每天，我们首先激活所有考试$s_i$等于今天，因为他们现在有资格进行准备。 
4. 如果当天是某项考试的考试日$i$，我们将这一天分配给考试评分者并且不允许进行准备。 这是强制性的，因为考试日期是固定的。 
5. 否则，我们会考虑当前正在进行的所有考试，这意味着它们的开始日期已经过去，并且仍然有剩余的准备工作。 其中，我们选择截止日期最短的考试$d_i$并且仍然需要准备。 
6. 如果存在此类考试，我们将当天指定为该考试的准备时间，并减少其剩余要求。 这种选择确保我们优先考虑最紧急的约束。 
7. 如果没有需要准备的现行考试，我们将安排这一天休息。 

经过一整天的处理后，我们检查所有考试是否已完成所需的准备。 如果有的话$c_i$仍然为正，我们输出$-1$，否则我们输出构建的时间表。 

### 为什么它有效

 该算法保持着一个关键的不变量：每天，在所有可行的选择中，如果两者都需要作业，我们绝不会推迟截止日期较早的考试而选择截止日期较晚的考试。 这可以防止截止日期倒置，即严格的考试被灵活的考试所取代。 

如果在某个时刻存在有效的时间表，那么总有一种方法可以重新安排任何时间表，以便可以在不破坏可行性的情况下将分配给较晚截止日期的准备日与较早截止日期交换。 这种交换论点证明了总是优先考虑可用考试中最近的截止日期的贪婪选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    exams = []
    exam_day = [-1] * (n + 1)
    
    for i in range(m):
        s, d, c = map(int, input().split())
        exams.append([s, d, c, i + 1])
        exam_day[d] = i + 1
    
    exams.sort()
    
    active = []
    remaining = [0] * (m + 1)
    start_map = [[] for _ in range(n + 2)]
    
    for s, d, c, idx in exams:
        start_map[s].append((d, idx))
        remaining[idx] = c
    
    res = [0] * (n + 1)
    
    import heapq
    
    for day in range(1, n + 1):
        for d, idx in start_map[day]:
            heapq.heappush(active, (d, idx))
        
        if exam_day[day] != -1:
            res[day] = m + 1
            continue
        
        while active and remaining[active[0][1]] == 0:
            heapq.heappop(active)
        
        if active:
            d, idx = heapq.heappop(active)
            if day < d:
                res[day] = idx
                remaining[idx] -= 1
            else:
                res[day] = 0
        else:
            res[day] = 0
    
    if any(remaining[i] > 0 for i in range(1, m + 1)):
        print(-1)
    else:
        print(*res[1:])

if __name__ == "__main__":
    solve()
```该实现直接反映了贪婪过程。 数组`exam_day`对强制考试日进行编码，以便立即处理。 这`start_map`当准备窗口打开时，结构会准确地激活考试。 

堆存储按截止日期排序的活动检查，确保始终首先考虑最紧急的检查。 这`remaining`array 跟踪还需要多少准备天数，并且过时的堆条目会被懒惰地跳过。 

一个微妙的细节是，我们必须避免在考试当天或之后分配准备工作，因此我们检查`day < d`在进行准备任务之前。 如果此条件失败，则该天将被视为空闲，因为此时该考试不存在有效作业。

 ## 边缘情况

 一个重要的边缘情况是考试需要的准备天数超过其可用时间。 例如，如果在第 1 天宣布考试并在第 3 天安排考试​​，但需要 3 个准备天，则该间隔仅包含两个可用天。 该算法正确地处理了这个问题，因为基于堆的选择最终将耗尽有效天数，从而留下`remaining[i] > 0`, 触发`-1`。 

另一种情况是多个考试共用同一考试日。 由于考试日受约束是排他性的，因此这种情况不会发生，并且该算法依赖于这种唯一性来标记`exam_day[d]`安全。 

最后一个微妙的情况是，考试开始进行，但截止日期已经过去。 在这种情况下，条件`day < d`阻止作业，并且考试实际上被忽略，如果仍然不满足要求，则随后会强制失败。
