 ## 解决方案
 ## 问题理解

 我们得到一个代表文件名的短字符串。 唯一重要的约束是子字符串`"xxx"`在最终字符串内的任何地方都被禁止。 我们可以从任意位置删除字符，并且我们希望删除尽可能少的字符，这样就不会出现三个连续的字符`'x'`字符保留在结果字符串中。 

因此，该任务是单个字符串的最小化问题：我们必须中断连续的每次运行`'x'`字符，以便没有游程的长度为 3 或以上，同时删除尽可能少的字符。 

输入大小很小，字符串的长度最多为 100。这立即表明任何线性扫描甚至稍微复杂一点的贪婪逻辑就足够了。 甚至一个$O(n^2)$方法可以轻松通过，但问题的结构强烈表明单次贪婪解决方案就足够了。 

一个天真的但重要的观察是，运行之外的删除`'x'`对这个约束从来没有帮助。 仅连续的序列`'x'`字符很重要，因为任何禁止的模式都必须完全来自它们。 

一些边缘情况在概念上很重要。 

一种情况是像这样的字符串`"xx"`或者`"axxa"`。 不需要删除，因为没有长度为 3 的游程。正确答案是 0。 

另一种情况是`"xxx"`。 我们必须删除至少一个字符才能中断运行，所以答案是 1。 

稍微长一点的情况，比如`"xxxx"`需要删除至少一个字符以减少任何由此产生的运行`'x'`最多 2 个。例如，删除一个字符会产生`"xxx"`，但这仍然无效，因此至少需要再删除一次，使答案为2。 

粗心的方法往往会失败，因为仅检查是否`"xxx"`存在并删除某处的单个字符，而不考虑更长的运行。 这对于长度 3 有效，但对于长度 4 或更长会立即中断。 

## 方法

 暴力解决方案将尝试删除所有位置子集，重建结果字符串，并检查它是否包含`"xxx"`。 这是正确的，但一般来说完全不可行，因为有$2^n$子集，其中对于$n = 100$是一个天文数字。 

约束的结构使问题成为局部的：只有连续的块`'x'`事情。 我们可以从左到右处理字符串并处理连续的每个最大片段，而不是全局考虑删除`'x'`独立。 

在一个块内$k$连续的`'x'`字符，我们要确保最多保留 2 个。 如果$k \le 2$，不需要删除任何内容。 如果$k \ge 3$，我们必须准确删除$k - 2$字符，因为保留超过 2 个字符会违反条件，而保留少于 2 个字符只会增加不必要的删除。 

关键的见解是一个块中的删除不会影响任何其他块。 因此，最优策略就是将每次运行的超过 2 的部分相加`'x'`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(2^n \cdot n)$|$O(n)$| 太慢了|
 | 最佳|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们扫描一次字符串，同时跟踪连续的`'x'`人物。 

1. 初始化一个答案计数器和一个变量来跟踪当前游程长度`'x'`。 这个游程长度代表有多少个连续的`'x'`到目前为止我们已经看到的角色。 
2. 逐个字符地遍历字符串。 
3. 如果当前字符是`'x'`，增加游程长度。 这扩展了当前块。 
4. 如果当前字符不是`'x'`，我们完成了前一个块。 如果游程长度至少为 3，我们添加`run_length - 2`答案因为只有两个`'x'`角色可以在不违反规则的情况下保留。 然后将游程长度重置为零。 
5. 循环结束后，如果字符串以以下结尾，我们必须处理最后一个块`'x'`。 同样的规则适用：任何超过 2 次的跑动都会贡献`run_length - 2`删除。 

为什么它起作用是基于结构不变量：在每一点，我们都充分考虑了所有已完成的连续运行中所需的删除`'x'`角色，并且没有运行与另一个运行交互。 每个块都是独立的，因为禁止模式仅取决于邻接性，并且一个块内的删除不能创建或修复另一个块中的违规。 因此，对局部最优修复进行求和就可以得到全局最优解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())
s = input().strip()

ans = 0
run = 0

for ch in s:
    if ch == 'x':
        run += 1
    else:
        if run >= 3:
            ans += run - 2
        run = 0

# finalize last run
if run >= 3:
    ans += run - 2

print(ans)
```该实现保留单个运行计数器`run`对于连续的`'x'`人物。 关键细节是循环后的最终刷新，因为以`'x'`否则将使其最后一段未处理。 

一个常见的错误是忘记了最后一步，这会导致当字符串以长序列结尾时计数不足。`'x'`。

这表明只需要一次删除就可以打破三个的单次运行`'x'`人物。 

现在考虑`"xxxx"`。 

| 索引 | 查尔 | 行程长度| 行动| 回答 |
 | --- | --- | --- | --- | --- |
 | 1 | x| 1 | 继续 | 0 |

这证实了更长的运行需要按比例减少，而不仅仅是删除单个字符。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input().strip())
    s = input().strip()

    ans = 0
    run_len = 0

    for ch in s:
        if ch == 'x':
            run_len += 1
        else:
            if run_len >= 3:
                ans += run_len - 2
            run_len = 0

    if run_len >= 3:
        ans += run_len - 2

    return str(ans)

# provided samples
assert run("6\nxxxiii\n") == "1"

# custom cases
assert run("3\nxxx\n") == "1"
assert run("4\nxxxx\n") == "2"
assert run("5\naxxxa\n") == "1"
assert run("2\nxx\n") == "0"
assert run("7\nxxxxxxx\n") == "5"
```| 测试输入| 预期产出 | 它验证了什么 |

 |`"xxx"`|`1`| 最小禁止情况|
 |`"xxxx"`|`2`| 长期运行处理|
 |`"axxxa"`|`1`| 内部块处理|
 |`"xx"`|`0`| 无需删除 |

 ## 边缘情况

 对于像这样的字符串`"axxxxa"`，该算法隔离了四个内部运行`'x'`人物。 当它扫描时，它会构建 4 的游程长度，然后在命中时重置`'a'`，添加`4 - 2 = 2`到答案。 周边`'a'`字符不影响计算。 

为了`"xxxxxxx"`，运行次数增长到 7，并且仅在最后进行处理。 最后的同花添加`7 - 2 = 5`，正确处理最坏情况的连续块。 

两种情况都证实了每个最大的不变量`'x'`片段独立地减少到长度最多为2，并且删除最少。
