 ## 解决方案
 ## 问题理解

 我们得到了一个整数序列，并且可以通过选择将其减少 1、增加 1 或保持不变来独立地稍微“调整”每个元素。 应用这些微小的调整后，我们希望结果序列形成算术级数，这意味着连续元素之间的差异在整个数组中变得恒定。 

我们的目标不仅仅是决定这是否可行，而是尽量减少我们实际修改的位置数量。 如果我们对某个位置应用 +1 或 -1，则该位置算作已修改。 保持它不变不需要任何成本。 

关键的困难来自于每个元素都有三个可能的最终值，因此所有修改序列的空间都是指数的。 由于元素多达 100,000 个，因此无法强制执行所有调整组合。 

考虑约束的一个有用方法是，任何有效的解决方案完全由两个参数确定：修改后的第一个元素和公差。 一旦这些被修复，每个元素的目标值就会被强制。 唯一剩下的自由是选择每个位置是否与其原始值匹配，或者必须精确移动 1 以匹配目标。 

当即使在修改之后也无法形成有效的算术级数时，就会出现微妙的边缘情况。 例如，如果所需的差异迫使某些元素与其原始值相差超过一个单位，则该候选级数无效。 另一个边缘情况是长度为 1 或 2 的序列，其中任何值始终形成算术级数，因此答案始终为零。 

## 方法

 暴力方法会尝试所有可能的调整组合，这意味着每个元素都处于三种状态之一。 这导致了 3^n 种可能性，对于 n 达到 100,000 来说这是完全不可行的。 

一种更结构化的蛮力方法是观察算术级数是由其前两个元素定义的。 如果我们猜测前两个位置的调整值，则序列的其余部分将被强制。 由于前两个位置各有 3 个选项，因此我们只有 9 个候选起始对。 对于每一对，我们传播所需的公差，并检查每个元素是否可以在其原始值的 ±1 范围内匹配。 

这将问题简化为恒定数量的线性扫描。 关键的见解是，一旦第一项和差值被固定，其他所有项都是唯一确定的，因此我们不再探索组合，而只是验证一致性。 

在验证期间，每个位置贡献 0 成本（如果已经正确）或 1 成本（如果我们必须调整 ±1）。 如果任何位置与目标的偏差超过 1，则该候选进度无效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(3^n) | O(3^n) | O(1) | O(1) | 太慢了|
 | 尝试前两个位置（9例） | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们依赖这样一个事实：算术级数是由它的前两个值唯一确定的。 

### 步骤

 1. 提取第一个元素的候选值：$b_0 - 1, b_0, b_0 + 1$。 对第二个元素执行相同的操作。 这些最多定义 9 个起始配置。 

每个配置代表位置 0 和 1 的调整值的可能选择。 
2. 对于每个候选对$(x_0, x_1)$，计算公差$d = x_1 - x_0$。 

此步骤是必要的，因为一旦前两项被固定，所有后面的项都必须遵循这个精确的差异。 
3. 初始化所需修改的计数器。 如果$x_0 \neq b_0$，添加一个。 如果$x_1 \neq b_1$，添加一个。 

这说明了我们是否在前两个位置使用了 ±1 调整。 
4. 迭代数组的其余部分。 对于每个索引$i \ge 2$，计算所需的值：$$target_i = x_0 + i \cdot d$$5. 检查每个职位的可行性：

 如果$|b_i - target_i| > 1$，这个候选者是不可能的，必须立即丢弃。 

否则，如果$b_i \neq target_i$，增加修改计数器。 
6. 跟踪所有有效候选对的最小成本。 
7. 如果没有有效的候选对，则返回-1。 否则返回最小成本。 

### 为什么它有效

 每个有效的最终序列都必须是算术级数，因此它必须有一些第一项和公差。 因为每个元素最多可以改变一个，所以真正的前两个元素必须位于集合中$\{b_0-1, b_0, b_0+1\}$和$\{b_1-1, b_1, b_1+1\}$。 因此，每个有效解决方案都由 9 个候选起始对之一覆盖。 

一旦一对被固定，序列的其余部分就没有自由了。 与原始数组的任何偏差都会产生一种成本，任何大于 1 的偏差都会导致候选不可能。 这保证了我们既不会错过有效的解决方案，也不会接受无效的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    b = list(map(int, input().split()))

    if n <= 2:
        print(0)
        return

    INF = 10**18
    ans = INF

    for a0_delta in (-1, 0, 1):
        for a1_delta in (-1, 0, 1):
            x0 = b[0] + a0_delta
            x1 = b[1] + a1_delta

            d = x1 - x0
            cost = 0

            if x0 != b[0]:
                cost += 1
            if x1 != b[1]:
                cost += 1

            ok = True

            for i in range(2, n):
                expected = x0 + i * d
                diff = b[i] - expected

                if abs(diff) > 1:
                    ok = False
                    break

                if diff != 0:
                    cost += 1

            if ok:
                ans = min(ans, cost)

    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```该实现显式枚举前两个元素的所有有效初始扰动。 序列的其余部分在每个候选者的单次传递中进行验证。 成本计算与每个元素是否已经等于其目标或需要 ±1 调整直接相关。 

一个常见的陷阱是忘记我们必须使用绝对差来检查可行性。 另一个是在不修复前两个值的情况下错误地增量重新计算差异，这可能导致传播不一致。

 ## 边缘情况

 关键的边缘情况是最佳解决方案不使用原始的第一或第二值。 例如，如果将两者移动 ±1 会产生有效的级数，但保持它们固定不会产生有效级数，则算法仍必须探索这些候选者。 所有 9 个起始状态的枚举保证了这一点被覆盖，因为 (b0±1, b1±1) 始终包含在内。 

当早期位置看起来有效但后来的位置超过 ±1 容差时，会出现另一种边缘情况。 在这种情况下，算法必须立即拒绝整个候选者，而不是试图贪婪地“修复”以后的不匹配。 绝对差异检查严格执行这一点，防止错误的部分接受。 

最后，长度为 1 或 2 的序列绕过所有逻辑，因为任何两个数字总是形成算术级数。
