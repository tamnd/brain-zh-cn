 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，并要求通过删除重复项来压缩它，但有一个特定的规则：对于每个不同的值，只能保留它在数组中最后一次出现的值。 最终的输出不仅仅是一组唯一值，而是原始序列的过滤版本，其中早期出现的重复数字消失，而最后出现的数字保留在原位。 

关键限制是数组大小最多为 50。这立即排除了任何性能问题。 即使是对照所有其他元素检查每个元素的方法也能在时间限制内顺利运行，因为操作总数最坏的情况下也只有几千次。 这意味着我们可以完全关注清晰度和正确性，而不是优化压力。 

此类问题的一个微妙问题是“保留最后一次出现”是方向相关的。 保留我们第一次看到某个值的天真前向扫描会产生错误的答案。 例如，在数组中`[1, 2, 1]`，保留第一次出现的产量`[1, 2]`，但正确的输出是`[2, 1]`因为第二个`1`是必须留下的。 如果我们在向前扫描时动态删除元素，则会出现另一种失败情况，因为索引移位可能会导致后面的元素被跳过或错误处理。 例如，删除重复项`5`在`[5, 5, 6]`从左到右迭代时可能会意外地跳过检查，具体取决于实现。 

正确的推理必须基于“最右边的事件”的概念，从末尾而不是从头开始扫描本质上更容易推理。 

## 方法

 暴力策略会考虑每个元素并向右搜索以确定它是否再次出现。 如果以后没有出现，我们就保留它； 否则我们会丢弃它。 这在逻辑上是正确的，因为它直接编码了“最后一次出现”的定义。 然而，对于每个`n`元素，我们可以扫描到`n`领先的位置，导致最坏情况的复杂性约为`n^2`检查。 

尽管`n ≤ 50`尽管这在实践中变得微不足道，但问题的结构提出了一种更优雅的方法。 我们可以扭转我们的视角，而不是重复地向前搜索：从右到左处理数组，同时记录我们已经包含的值。 我们在这个反向遍历中第一次遇到一个值正是它在原始数组中最后一次出现。 这一观察结果完全消除了重复扫描的需要。 

我们维护一套可见的价值观。 当我们从数组的末尾移动到开头时，我们只获取以前没有见过的元素。 这保证了每个值在与其最后一次出现对应的点处恰好添加一次。 以逆序收集结果后，我们将其反转以恢复正确的输出顺序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（向右扫描每个元素）| O(n²) | O(1) | O(1) | 已接受 |
 | 最佳（带设置的反向扫描）| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们通过从数组末尾扫描来构建答案，以便我们首先遇到最后一次出现的每个值。 

1. 从数组的最后一个元素开始，向左移向第一个元素。 这个方向确保我们第一次看到一个值是它在原始序列中最右边出现的位置。 
2. 维护一个存储我们已包含在结果中的值的集合。 该集合代表已考虑最后一次出现的所有值。 
3. 对于向后扫描期间的每个元素，检查它是否已经在集合中。 

如果它不存在，则意味着我们当前处于它的最后一次出现位置，因此我们将其添加到结果中并将其插入到集合中。 
4. 如果该元素已在集合中，则跳过它，因为它的最后一次出现是在扫描的较早阶段遇到的。 
5. 向后遍历完成后，采集到的结果相对于想要的输出是倒序的，所以在打印之前先倒序一次。 

### 为什么它有效

 不变的是，在向后扫描期间的任何点，该集合恰好包含那些在原始数组中最右边出现的值已经被处理和存储的值。 因为我们从右向左遍历，所以第一次遇到的值恰好对应于它在原始数组中的最后一个位置。 这保证了每个值只添加一次，并且永远不会在其最终出现之前添加。 反转收集的序列会恢复最后出现的原始相对顺序，因为它们在向后遍历中的顺序与其在原始数组中的顺序相反。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    seen = set()
    res = []
    
    for i in range(n - 1, -1, -1):
        if a[i] not in seen:
            seen.add(a[i])
            res.append(a[i])
    
    res.reverse()
    
    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```该解决方案读取数组，然后从右到左迭代。 这`seen`set 确保我们只保留每个值在这个反向遍历中第一次出现的时间，它对应于它在原始数组中的最后一次出现。 结果列表以相反的顺序构建，因此最终的反转会恢复正确的输出顺序。 

唯一微妙的实现细节是反转步骤是强制性的。 如果没有它，输出将按照元素最后一次出现的顺序从右到左列出元素，这不是所需的格式。

 ## 边缘情况

 对于像这样的单元素数组`[7]`，反向扫描立即添加`7`因为结果是看不见的。 不存在其他元素，因此输出保持不变`[7]`，它满足单个值通常是它自己的最后一次出现的要求。 

对于所有元素都相同的数组，例如`[1, 1, 1, 1]`，向后扫描添加`1`在最后一个位置，然后跳过所有较早的出现，因为它们已经在`seen`放。 结果仅包含一个元素，这是正确的，因为必须保留最右边的出现位置。 

对于像这样的严格递增数组`[1, 2, 3, 4]`，每个元素都是在向后扫描期间首次遇到的，因此所有元素都被包括在内。 反转会保持原始顺序不变，从而确认该算法不会删除不必要的元素。
