 ## 解决方案
 ## 问题理解

 我们得到了公交车上乘客数量的一系列记录变化。 每个值都告诉我们乘客数量在停靠后如何变化，因此如果我们将起始乘客数量表示为$x$，然后在每次停止后，我们重复添加给定的增量并获得运行的前缀和过程。 

公交车有一个硬性约束：每时每刻，乘客数量必须停留在$0$和$w$，包含在内。 这不仅适用于每次记录的停止之后，还适用于第一个停止之前（其中计数为$x$）。 

任务不是重建一个有效场景，而是计算初始乘客数有多少个整数值$x$有效，以便所有中间前缀和保持在允许的范围内。 

这些限制已经表明$O(n)$或者$O(n \log n)$需要解决方案。 和$n \le 1000$，甚至一个$O(n^2)$方法可能会通过，但是任何试图直接在很宽的范围内模拟所有可能的起始值的方法$10^9$是不可能的。 

一个关键的微妙之处是初始值$x$不受输入限制，仅隐含地受可行性限制。 天真的读者可能会尝试迭代所有可能的起始值$0$到$w$，但由于负前缀和，实际可行范围可能会超出中间状态的范围。 

一种常见的失败案例来自于忽略中间约束。 例如，如果前缀总和低于零，则全局看起来有效的起始值可能仍会在某个步骤违反约束。 同样，如果前缀和超过一定范围，也会使起始无效。 正确性取决于跟踪整个前缀和轨迹，而不仅仅是其最终值。 

## 方法

 核心观察是步骤中的乘客数量$i$可以写成：$$x + p_i$$在哪里$p_i$是记录的更改的前缀和$i$。 

因此，每个约束都变为：$$0 \le x + p_i \le w$$重新排列给出了间隔约束$x$:$$-p_i \le x \le w - p_i$$因此，每个前缀和贡献一个有效起始值的区间。 最终答案是所有这些区间的交集$i$，包括隐式前缀和$p_0 = 0$。 

蛮力的想法是测试所有可能的$x$从$0$到$w$并模拟所有步骤，这会花费$O(wn)$，太大了，因为$w$可以是$10^9$。 上面的观察将问题转化为维护间隔的交集，将所有内容简化为仅跟踪两个值。 

所有约束的交集本身就是一个区间$[L, R]$，逐步更新。 每个前缀和都会缩小这个间隔。 如果在任何时候间隔变空，则不存在有效的起始值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nw)$|$O(1)$| 太慢了|
 | 区间交集|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们定义$p$作为变化的运行前缀和。 

1. 初始化$p = 0$，并设置有效范围$x$作为$L = 0$,$R = w$。 这反映了这样一个事实：最初公交车必须已经满足容量限制。 
2. 对于每个记录的更改$a_i$,更新前缀和$p = p + a_i$。 这表示从初始状态到步骤的净转变$i$。 
3. 转换条件$0 \le x + p \le w$进入约束条件$x$，产生区间$[-p, w - p]$。 
4. 将此区间与当前有效范围相交：$L = \max(L, -p)$,$R = \min(R, w - p)$。 

这确保我们只保留到目前为止满足所有约束的起始值。 
5. 如果在任何时候$L > R$，提前停止，因为不存在有效的初始值。 
6. 处理完所有步骤后，答案是$R - L + 1$，因为最终间隔中的所有整数都是有效的起始乘客计数。 

### 为什么它有效

 每一步都对初始值施加线性约束$x$。 由于所有约束的形式为$x \in [\ell_i, r_i]$，有效集合是区间的交集。 区间的交集是关联的，可以增量维护而不会丢失信息。 该算法在每一步之后准确保留所有可行起始值的集合，因此不会丢弃有效的解决方案，也不会引入无效的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, w = map(int, input().split())
    a = list(map(int, input().split()))

    prefix = 0
    L, R = 0, w

    for x in a:
        prefix += x

        L = max(L, -prefix)
        R = min(R, w - prefix)

        if L > R:
            print(0)
            return

    print(max(0, R - L + 1))

if __name__ == "__main__":
    solve()
```该实现保留单个运行前缀和并在每一步更新可行范围。 界限$L$和$R$始终表示迄今为止看到的所有约束的交集。 提前退出时$L > R$一旦可行性被破坏，就可以避免不必要的计算。 

一个微妙的点是确保最终答案被正确限制：如果约束是一致的，$R - L + 1$计算所有整数初始值。 如果出现不一致，该函数已经返回零。

 ## 边缘情况

 当所有变化都为零时，就会出现一种边缘情况。 在这种情况下，前缀和始终保持为零，因此每个起始值$0$到$w$是有效的。 算法保持$L=0$和$R=w$不变，生产$w+1$，它与正确的计数相匹配。 

另一个边缘情况是约束立即变得不可能。 例如，如果$w = 3$第一个变化是$+5$，那么前缀和已经超出了任何起始值的可行范围。 间隔变为$[L, R] = [0, 3] \cap [-5, -2]$，它是空的，并且算法无需进一步处理即可正确输出零。 

最后一个微妙的情况是中间前缀总和强制约束从最终总和中不可见。 第二个工作示例证明了这一点：即使总变化很小，中间积累也会限制有效的启动。 区间交集方法会自动捕获这一点，因为它会评估每个前缀的约束，而不仅仅是末尾的约束。
