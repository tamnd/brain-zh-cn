 ## 解决方案
 ## 问题理解

 我们得到一个数字$n$它是以一种非常具体的方式构建的。 有人秘密选择了一个整数$x$，然后创建另一个数字$y$通过在右侧添加一个或多个零$x$。 这意味着$y = x \cdot 10^k$对于某些人来说$k \ge 1$。 最后只透露了总和$n = x + y$。 我们的任务是恢复所有可能的原始内容$x$可以产生给定的$n$。 

所以结构不是任意相加的。 它总是具有以下形式$$n = x + x \cdot 10^k = x(1 + 10^k)$$对于某个整数$k \ge 1$， 和$x$必须是正整数。 我们被要求找到所有这些有效的$x$对于每个测试用例。 

约束条件允许$n$最多$10^{18}$直至$10^4$测试用例。 这立即排除了任何尝试所有可能的数字分割或暴力候选的行为$x$最多$n$。 甚至$O(n)$每次测试都是不可能的，甚至$O(\sqrt{n})$在最坏的情况下，每次测试都会太慢。 

一个微妙的边缘情况来自这样一个事实：该结构取决于十次方的转变。 如果我们尝试猜测$k$错误地或假设固定长度的数字分割，我们可能会错过有效的解决方案或过多计算无效的解决方案。 

例如，如果$n = 1111$，存在有效答案：

 -$x = 11$， 自从$11 + 1100 = 1111$-$x = 101$， 自从$101 + 1010 = 1111$只检查相同长度的前缀后缀匹配的天真尝试将会失败$x = 11$。 相反，检查所有子串作为候选$x$如果不强制执行代数约束，就会产生许多无效的候选者。 

## 方法

 直接的暴力策略是尝试一切可能的方法$x$从$1$到$n$, 计算$y = n - x$，并检查是否$y$等于$x$带有一些尾随零。 这是有效的，因为它直接强制执行定义，但它需要$O(n)$每个测试用例进行检查，当$n$可以大到$10^{18}$。 

即使我们仅通过迭代数字的前缀来进行优化$n$，我们仍然需要通过除法或字符串重建来验证每个候选，并且候选的数量仍然与位数乘以可能的移位成正比。 

关键的观察结果是结构$n = x(1 + 10^k)$将问题转化为具有非常特殊形式的除数搜索问题。 对于每个固定$k$，值$(1 + 10^k)$已知，并且$x$必须完全是$n / (1 + 10^k)$如果可以整除的话。 自从$10^k$有效数量呈指数级增长$k$受数字位数的限制$n$，最多为 18。这将问题简化为仅检查一小部分候选者。 

因此我们可以列举所有可能的$k$，计算候选分母$d = 10^k + 1$，并测试是否$n$可以整除$d$。 如果是这样，我们就恢复了$x$。 这是有效的，因为搜索空间是对数的$n$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解 x |$O(n)$|$O(1)$| 太慢了|
 | 枚举 k（10 的幂）|$O(\log n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 对于每个测试用例，请阅读$n$并准备一个空的答案列表。 我们将收集所有有效的$x$价值观。 
2. 迭代可能的值$k$，从 1 开始，同时$10^k < n$。 每个$k$表示形成时附加了多少个零$y = x \cdot 10^k$。 
3. 对于每个$k$, 计算$d = 10^k + 1$。 这直接来自于重写方程$n = x(1 + 10^k)$。 
4. 检查是否$n \mod d = 0$。 如果不是，则无效$x$为此而存在$k$，所以继续。 
5. 如果可整除，计算$x = n / d$。 这是一个候选解决方案。 
6. 商店$x$如果是积极的。 自从$d > 1$，当除法精确时，正性得到保证，但我们仍然在概念上保留检查。 
7. 尝试完所有方法后$k$，对收集到的进行排序$x$值并输出它们。 需要排序，因为不同$k$值可能会产生非单调顺序的结果。 

### 为什么它有效

 每个有效的构造都满足$n = x(1 + 10^k)$对于某个整数$k \ge 1$。 反之，任意$k$为此$1 + 10^k$划分$n$产生一个候选人$x$重建一个有效的$y = x \cdot 10^k$。 该算法枚举了所有可能的$k$，并且对于每一个，它要么拒绝要么重建恰好一个可能的$x$。 不会错过任何有效的解决方案，因为每个有效的表示都恰好对应于一个这样的解决方案$k$，并且不能添加无效解，因为整除性严格执行原始方程。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        res = []

        pow10 = 10
        k = 1

        while pow10 < n:
            d = pow10 + 1
            if n % d == 0:
                x = n // d
                res.append(x)
            pow10 *= 10
            k += 1

        if not res:
            print(0)
        else:
            res.sort()
            print(len(res))
            print(*res)

if __name__ == "__main__":
    solve()
```实施遵循以下观察：只有十的幂才重要。 我们维持$10^k$增量而不是每次重新计算，这避免了不必要的求幂开销。 

循环停止时$10^k \ge n$因为超过那个点$1 + 10^k$已经超过$n$，使得整除变得不可能。 

最后排序可确保输出顺序正确，即使较大$k$不一定对应较小的$x$。

 ## 边缘情况

 一个重要的边缘情况是当$n$正好是十的幂或接近十的幂。 例如，$n = 1000000000000000000$。 算法迭代$k$，但每一个$10^k + 1$要么超过$n$或者不分割它。 循环提前停止，并且没有生成候选，正确输出 0。 

另一个边缘情况是当多个值$k$产生有效的结果。 为了$n = 1111$， 两个都$k = 1$和$k = 2$工作。 该算法自然会收集两者，因为每个$k$经过独立测试，排序确保输出顺序正确。 

最后一个微妙的情况是整除性成立但计算出的$x$在原来的构造下没有任何意义。 这不可能发生，因为$n \mod (10^k + 1) = 0$意味着精确的代数重建$n = x(1 + 10^k)$，它唯一地确定了一个有效的$y = x \cdot 10^k$，保留所需的结构而无需额外检查。
