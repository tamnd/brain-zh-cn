 ## 解决方案
 ## 问题理解

 每笔交易都让我们准确购买$3^x$西瓜为$$3^{x+1} + x \cdot 3^{x-1}$$硬币。 

我们需要准确购买$n$西瓜。 我们最多可能会用到$k$交易。 在所有有效的方法中，我们希望总成本最小。 

的价值观$n$和$k$一样大$10^9$，并且最多有$10^4$测试用例。 任何线性依赖于的算法$n$立刻就不可能了。 有用的观察是，三的幂增长得非常快。 自从$$3^{19} > 10^9,$$每个数字直到$10^9$只有大约二十个三进制数字。 这强烈表明该解决方案应该适用于三元表示$n$，而不是针对单个西瓜。 

一个微妙的点是，限制是“最多$k$交易”，而不是“完全$k$交易”。粗心的解决方案可能会尝试强制交易计数等于$k$，即使该计数无法达到。 

例如：```
n = 3, k = 2
```唯一的表述是：$$3$$一笔交易，或$$1+1+1$$与三笔交易。 

两笔交易是不可能的。 正确答案是 10，使用一笔交易。 

另一个容易犯的错误是假设最小和最大之间的每笔交易都是可以实现的。 

例如：```
n = 9
```可能发生的交易计数为：$$1,3,5,7,9$$因为每次拆分都会使交易数量恰好增加两倍。 甚至计数也从未出现。 

第三个陷阱是可行性。 如果最小可能交易数量已超过$k$，没有有效的解决方案。 

例如：```
n = 8
```其三元表示为$22_3$，这已经需要四笔交易：$$8 = 3 + 3 + 1 + 1.$$如果$k=3$，答案是$-1$。 

## 方法

 蛮力观点是将每个解决方案视为三幂的多重集，其总和为$n$。 我们可以尝试每种幂的所有可能计数并计算最便宜的有效组合。 

这是正确的，但完全不切实际。 即使对于中等值$n$，代表数量呈爆炸式增长。 和$n$最多$10^9$，穷举搜索是没有希望的。 

关键的观察来自于重写交易价格。 

对于规模交易$3^x$,$$3^{x+1}+x3^{x-1} = 3\cdot 3^x + x3^{x-1}.$$总结所有交易得出$$\text{cost} = 3n + \sum c_x \, x3^{x-1},$$在哪里$c_x$是规模的交易数量$3^x$。 

期限$3n$是固定的。 整个优化问题实际上就是最小化$$E=\sum c_x \, x3^{x-1}.$$现在考虑单笔交易的规模$3^x$。 我们可以用三笔规模的交易来取代它$3^{x-1}$。 

西瓜数量保持不变。 

交易数量增加了两笔。 

额外费用变化自$$x3^{x-1}$$到$$3(x-1)3^{x-2} = (x-1)3^{x-1}.$$减少量为$$3^{x-1}.$$这是至关重要的事实。 

每次分割：

 1. 将交易数量增加 2 倍。 
2. 将目标精确减少$3^{x-1}$。 

最小交易表示只是以下的三元表示$n$。 从那里开始，所有其他表示都是通过将较大的幂重复分成三个较小的幂来获得的。 

问题变成：

 从三元表示开始。 我们被允许进行一定次数的分割。 每次分割的利润等于$3^{x-1}$。 我们希望尽可能多的交易，但不超过$k$，因为每次拆分都会严格降低成本。 然后我们首先选择最有利可图的分割。 

三进制位数只有二十左右，所以一切都可以在对数时间内计算出来。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 最佳| O(log n) | O(log n) | 已接受 |

 ## 算法演练

 1. 转换$n$成三元。 
2.让$a_x$是位置上的三进制数字$x$。 

最小交易表示完全使用$a_x$交易规模$3^x$。 
3. 计算$$D_0=\sum a_x,$$可能的最小交易数量。 

如果$D_0 > k$，不存在有效的解决方案，答案是$-1$。 
4. 计算最小交易表示的额外成本：$$E_0=\sum a_x \cdot x3^{x-1}.$$5.让$$T=\min(k,n).$$任何表示都不能使用超过$n$交易是因为最小的交易只能购买一个西瓜。 
6. 每次分割都会使交易计数恰好增加两倍，因此所有可到达的交易计数具有与$D_0$。 

选择最大可达交易数不超过$T$：$$D= \begin{cases} T,& T\equiv D_0\pmod 2\\ T-1,& \text{otherwise} \end{cases}$$7. 所需分割数为$$S=\frac{D-D_0}{2}.$$8. 计算每个级别存在多少个分割机会。 

让$N_x$是大小的节点总数$3^x$如果所有较大的权力完全分裂，这种情况就可能出现。 

这些满足$$N_x=a_x+3N_{x+1}.$$9. 处理级别从最大到最小。 

水平上的分裂$x$产生利润$$3^{x-1}.$$由于更高的级别总是带来更大的利润，因此贪婪地从最大的剩余级别中获取尽可能多的分割。 
10. 让所选的总利润$S$分裂是$R$。 

最小化的额外成本是$$E=E_0-R.$$11.答案是$$3n+E.$$### 为什么它有效

 三元表示给出了交易数量最少的唯一表示。 每一个有效的表示都可以通过重复替换一个来获得$3^x$与三个$3^{x-1}$。 

每个此类操作都会准确地改变交易计数$+2$并精确地减少目标$3^{x-1}$。 由于每次拆分都会严格提高成本，因此最优解决方案始终使用不超过的最大可达交易数$k$。 

在执行固定数量分割的所有方法中，选择较高级别的分割总是至少与选择任何较低级别的分割一样有利可图，因为它的利润更大。 因此，从最高级别向下处理分割机会可以最大限度地减少总量。 这产生了尽可能最低的成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, k = map(int, input().split())

        digits = []
        x = n
        while x:
            digits.append(x % 3)
            x //= 3

        m = len(digits)

        pow3 = [1] * max(1, m)
        for i in range(1, m):
            pow3[i] = pow3[i - 1] * 3

        d0 = sum(digits)

        if d0 > k:
            out.append("-1")
            continue

        e0 = 0
        for i, d in enumerate(digits):
            if i > 0:
                e0 += d * i * pow3[i - 1]

        tmax = min(k, n)
        if (tmax - d0) & 1:
            d = tmax - 1
        else:
            d = tmax

        splits = (d - d0) // 2

        N = [0] * m
        N[-1] = digits[-1]
        for i in range(m - 2, -1, -1):
            N[i] = digits[i] + 3 * N[i + 1]

        reduction = 0
        s = splits

        for level in range(m - 1, 0, -1):
            take = min(s, N[level])
            reduction += take * pow3[level - 1]
            s -= take
            if s == 0:
                break

        answer = 3 * n + (e0 - reduction)
        out.append(str(answer))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```三进制数字形成最小交易表示。 变量`d0`存储其交易数量并立即处理不可行的情况。 

数量`e0`是成本超出固定基线的额外部分`3 * n`。 

奇偶校验调整很容易被错过。 每次拆分都会使交易计数增加两倍，因此可达到的计数保持奇偶校验。 代码选择不超过两者的最大可达计数`k`和`n`。 

数组`N`是最重要的实施细节。`N[level]`计算完全扩展更大级别后可能出现的该大小的所有可能节点。 每个这样的节点在该级别贡献一个潜在的分裂。 

所有算术都适合 Python 整数。 最大的答案是几十亿的数量级。

 ## 边缘情况

 考虑：```
1
3 2
```最小表示使用一笔规模为三的交易。 拆分它会产生三笔交易。 可达交易数只有 1 和 3。由于 2 不可达，算法调整为不超过 2 的最大可达数，即 1。答案变为 10。 

考虑：```
1
8 3
```三元表示为$22_3$，这已经需要四笔交易。 该算法计算`d0 = 4`，看到`4 > 3`，并立即输出`-1`。 

考虑：```
1
20 5
```最少代表使用四笔交易。 可达到的计数为 4、6、8...。 由于 5 的奇偶校验错误，因此不超过 5 的最大可达计数仍然是 4。该算法执行零分割并返回三元表示的成本。 这可以正确处理奇偶校验约束，而无需显式搜索表示。
