 ## 解决方案
 ## 问题理解

 这个问题给我们提供了一个卖家，他提供的西瓜的尺寸是三的幂。 每捆尺寸$3^x$成本$3^{x+1} + x \cdot 3^{x-1}$硬币。 买家想要的正是$n$西瓜的同时尽量减少交易数量，相当于大捆购买尽可能多的西瓜。 我们的任务是计算准确获取的最低成本$n$西瓜使用的交易数量最少。 

输入包括$t$测试用例。 每个测试用例都是一个整数$n$代表买家想要的西瓜数量。 每个测试用例的输出是一个整数：该测试用例的最小成本$n$。 

限制是这样的$n$可以达到$10^9$，并且最多可以有$10^4$测试用例。 这排除了检查每个可能的交易子集的任何解决方案，因为子集的数量将是指数级的。 我们需要一种方法来粗略地计算每个答案$O(\log n)$时间停留在时间限制内。 

对于刚刚超过三的幂的数字会出现一个微妙的边缘情况，例如$n = 4$。 一种幼稚的方法可能会尝试购买小于$n$然后用最小的捆覆盖其余部分。 这在这里可行，但需要仔细处理，以确保我们始终购买最少数量的交易 - 我们不能简单地选择最便宜的组合而不考虑捆绑数量。 

## 方法

 暴力方法将生成以下形式的所有可能交易$3^x$为了$x \ge 0$并尝试所有组合的总和精确到$n$。 这在原则上是正确的，但对于$n$最多$10^9$，可能的组合数量呈指数增长。 即使我们限制每种力量只使用一次，力量的数量也大约是 20 ($3^{19} \approx 10^9$），并且生成所有子集仍然是$2^{20} \approx 10^6$每个测试用例。 乘以$10^4$测试用例，这太慢了。 

关键的洞察是交易规模呈指数级增长。 这使我们能够像贪婪分解一样对待问题：我们总是考虑购买不超过的最大捆绑包$n$并重复其余部分。 然而，棘手的部分是成本与捆绑包大小并不呈线性关系。 每次直接挑选最大的捆绑包并不一定能最小化硬币的总成本。 相反，我们注意到每个数字$n$可以用“三元”形式表示：每个数字告诉我们有多少束$3^x$需要覆盖$n$。 最小交易数量对应于该三进制表示形式中的数字总和，在需要处理进位时进行四舍五入。 

我们可以通过重复计算最小交易数量来利用这一点，作为覆盖所需的 3 次幂之和$n$以及相关的成本公式。 每笔交易的规模$3^x$贡献了成本$2 \cdot 3^x$加上公式中可能有一些额外的线性分量，但主要技巧是表示$n$有效地作为三的幂的和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（子集和）| 每个测试用例 O(2^log3(n)) | O(log3(n)) | 太慢了$n$最多 10^9 |
 | 贪心三元分解 | 每个测试用例 O(log3(n)) | O(log3(n)) | 已接受 |

 ## 算法演练

 1. 预先计算最大的三的幂$3^x \le 10^9$。 这给出了所有可能的交易规模。 将它们按升序存储在列表中。 
2. 对于每个测试用例，请阅读$n$。 初始化一个变量`total_cost = 0`。 
3. 从三的最大幂向下迭代。 在每一步中，确定剩余的西瓜可以容纳多少个该大小的交易：`count = n // power`。 减去`count * power`从`n`。 
4. 对于每笔交易的规模$3^x$，用公式计算其成本$3^{x+1} + x \cdot 3^{x-1}$并添加`count * cost`到`total_cost`。 
5. 重复直到`n`达到零。 因为我们总是采用最大的可用捆绑包，所以交易数量被最小化。 
6. 输出`total_cost`。 

为什么有效：三的幂呈指数增长，因此首先使用最大的捆绑包可以确保更少的交易。 每笔交易的公式严格随着规模而增加，因此使用较小的交易只会增加交易总数或总成本。 通过分解$n$贪婪地求三的幂，我们保证最小的交易数量和正确的成本计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# precompute powers of 3 up to 10^9
powers = [1]
while powers[-1] * 3 <= 10**9:
    powers.append(powers[-1] * 3)

def deal_cost(x):
    if x == 0:
        return 3
    return 3**(x+1) + x * 3**(x-1)

t = int(input())
for _ in range(t):
    n = int(input())
    total_cost = 0
    remaining = n
    # iterate from largest power to smallest
    for i in reversed(range(len(powers))):
        count = remaining // powers[i]
        if count:
            total_cost += count * deal_cost(i)
            remaining -= count * powers[i]
    print(total_cost)
```该代码首先预先计算 3 的幂以避免重复求幂。 这`deal_cost`函数处理公式，包括特殊情况$x=0$。 对于每个测试用例，我们贪婪地选择尽可能大的包，直到所有西瓜都被买完。 使用反向迭代可确保最少的交易数量，并乘以`count`有效处理相同规模的多笔交易。 

## 工作示例

 **输入：`n = 8`**

 | 步骤| 考虑的功率| 计数 | 剩余 n | 总成本|
 | ---| ---| ---| ---| ---|
 | 3^1=3 | 3^1=3 3 | 2 | 8-6=2 | 2*10=20 | 2*10=20 |
 | 3^0=1 | 3^0=1 1 | 2 | 2-2=0 | 2-2=0 20+2*3=26 |

 该表确认使用两笔规模为 3 的交易和两笔规模为 1 的交易给出的最低成本为 26。 

**输入：`n = 10`**

 | 步骤| 考虑的功率| 计数 | 剩余 n | 总成本|
 | ---| ---| ---| ---| ---|
 | 3^2=9 | 3^2=9 9 | 1 | 10-9=1 | 10-9=1 1*28=28 | 1*28=28
 | 3^1=3 | 3^1=3 3 | 0 | 1 | 28 | 28
 | 3^0=1 | 3^0=1 1 | 1 | 1-1=0 | 1-1=0 28+3=31 | 28+3=31

 检查较小的组合：两笔大小为 3 的交易（6 个西瓜）+ 四笔大小为 1 的交易（4 个西瓜）将花费 2_10+4_3=32，该数字更高。 贪婪方法产生最小的成本。
