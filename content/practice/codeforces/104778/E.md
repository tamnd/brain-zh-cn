 ## 解决方案
 ## 问题理解

 我们有一本很大的书，页码从 1 到 n。 我们选择起始页 x，然后阅读从 x 到 n（含）的每一页。 每页都有一个数字，我们只关心该数字的最后一位数字。 

如果页面的最后一位数字等于 a 或 b，则该页面被视为“特殊”。 对于选定的起始页 x，我们计算后缀区间 [x, n] 中存在多少个特殊页。 任务是找到一个起始页 x，使得该计数恰好为 k，并且在所有有效选择中，我们必须输出最大可能的 x。 如果不存在这样的 x，我们输​​出 -1。 

关键的困难来自于 n 最大为 10^12 的约束。 这立即排除了任何迭代所有页面甚至显式存储它们的方法。 任何解决方案都必须依赖于最后一位数字模式的结构，而不是单个页面标识。 

当考虑贪婪地移动起点时，会出现一个微妙的问题。 [x, n] 中的特殊页数在 x 中是单调的，但不是严格线性的，因为只有最后一位数字很重要，并且这些数字每 10 个数字循环重复一次。 这种周期性是必不可少的。 

打破天真的思维的边缘情况包括 k 大于整本书中特殊页总数的情况。 例如，如果 n = 20、a = 4、b = 7，则特殊页为 4、7、14、17。如果 k = 5，则不存在解。 尝试“移动 x 直到计数与 k 匹配”的天真尝试最终会移过第 1 页并错误地假设 x = 1 有效。 

另一个棘手的情况是当 a = 0 或 b = 0 时。以 0 结尾的页面每 10 个数字出现一次，但仍必须一致地处理 10、20、30 等边界附近的行为。 

## 方法

 暴力方法会尝试从 1 到 n 的每个可能的起始页 x。 对于每个 x，我们将计算 [x, n] 中有多少页以数字 a 或 b 结尾。 每次这样的检查都需要 O(n)，因此总成本变为 O(n^2)，这对于 n 达到 10^12 来说是不可能的。 

即使改进固定 x 的计数，仍然会在所有 x 上留下外循环，这基本上太大了。 失败点不在于计数，而在于候选启动的数量。 

关键的观察结果是，条件仅取决于最后一位数字，每 10 个数字重复一次。 我们可以考虑 10 个连续数字的块，而不是处理单个页面。 每个完整块贡献固定数量的特殊页，仅由 a 或 b 是否出现在 0 到 9 之间决定。 

一旦我们知道 [x, n] 中有多少个完整周期，我们就可以使用算术在 O(1) 中计算计数。 这使我们能够快速检查任何候选者 x。 

现在任务变成：找到最大的 x 使得后缀 [x, n] 恰好包含 k 个特殊数字。 由于谓词“[x, n] ≥ k 中的特殊页计数”在 x 中是单调递减的，因此我们可以对计数下降到 k 的边界进行二分查找，然后验证相等性。 

我们将问题从扫描所有位置简化为对 x 进行一次二分搜索，检查次数为 O(log n)，每次 O(1)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了|
 | 最佳| O(log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们定义一个辅助函数 f(x)，它返回 [x, n] 中最后一位数字为 a 或 b 的页数。

1. 预先计算 0 到 9 中哪些数字是“特殊”的。 这是一个固定掩码，其中如果 d 等于 a 或 b，则数字 d 是特殊的。 这允许恒定时间检查。 
2. 定义一个函数 count_upto(t)，返回 [1, t] 中存在多少个特殊页。 我们使用 10 的完整块和余数段来计算此值。 对于每个完整的块，我们添加 0 到 9 中存在的特殊数字的数量。然后我们直接处理剩余的前缀。 
3. 使用前缀计数表示后缀计数：f(x) = count_upto(n) − count_upto(x − 1)。 这将问题转化为评估快速前缀函数。 
4. 通过计算 f(1) 检查可行性。 如果 f(1) < k，则任何后缀都不能包含 k 个特殊页面，因此我们输出 -1。 
5. 否则，对最小的 x 进行二分搜索，使得 f(x) ≤ k 不严格成立，或者等效地找到最大的 x，其中 f(x) = k。 由于 f(x) 随着 x 的增加而减小，因此我们可以搜索第一个 f(x) < k 的 x，然后后退一步。 
6. 二分查找后，验证候选 x，因为相等条件可能在边界处崩溃。 

二分查找的正确性依赖于f(x)的单调性：随着x的增加，区间[x,n]缩小，因此特殊页的数量不能增加。 

### 为什么它有效

 函数 f(x) 相对于 x 不增加，因为向右移动起点会从计数间隔中删除页面，并且不会添加新页面。 这种单调结构保证有效 x 值的集合形成整数后缀段。 二分查找正确识别该段的边界，检查边界可确保我们选择最大有效 x。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k, a, b = map(int, input().split())

    special = [0] * 10
    special[a] = 1
    special[b] = 1

    def count_upto(x):
        if x <= 0:
            return 0
        full = x // 10
        rem = x % 10
        base = sum(special) * full
        extra = 0
        for d in range(rem + 1):
            extra += special[d]
        return base + extra

    total = count_upto(n)

    def f(x):
        return total - count_upto(x - 1)

    if f(1) < k:
        print(-1)
        return

    lo, hi = 1, n
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if f(mid) >= k:
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```该实现依赖于将后缀查询转换为前缀计数，这避免了对每个候选 x 重新计算任何内容。 函数 count_upto 通过将数轴分成 10 的块和余数段来处理最后数字的周期结构。 

二分查找的目的是在 f(x) ≥ k 的条件下最大化 x，但由于 f 是递减的，这直接用正好 k 个特殊页来确定最大的有效起始点。 

一个常见的微妙之处是处理 x = 1，其中 x - 1 变为 0。前缀函数显式防止非正输入以避免算术错误。

| x| f(x) 计算思路 | f(x) | f(x) |
 | ---| ---| ---|
 | 29 | 29 仅第 29 页 → 不特别 | 0 |

 二分查找找到 f(x) = 3 时最大的 x，即 18。这符合后缀中恰好有 3 个页面以 0 或 8 结尾的要求。

 特殊页为 4, 7, 14, 17。总计数为 4，已经小于 k。

 ## 边缘情况

 对于 n = 10、k = 1、a = 0、b = 9 的情况，特殊页恰好是 9 和 10。正确答案是 x = 9，因为后缀 [9, 10] 包含两个特殊页，而 [10, 10] 仅包含一个，但不是最大的有效起始页，因为 9 仍然满足条件。 该算法计算 f(9) = 2 和 f(10) = 1，二分查找正确返回 10 作为 f(x) = 1 时的最大 x。 

对于 k 等于特殊页总数的情况，唯一有效的答案是 x = 1。算法检测到 f(1) = k，二分查找自然扩展到最左边的边界。 

对于a和b接近的情况，例如4和5，特殊页面的密度很高，但单调结构保持不变。 每 10 个块恰好贡献两个特殊位置，并且后缀计数仍然表现平稳，没有任何会破坏二分搜索假设的不连续性。
