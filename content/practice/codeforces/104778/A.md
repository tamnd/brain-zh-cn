 ## 解决方案
 ## 问题理解

 我们给出了三个正整数，表示三个刚性段的长度。 在一次移动中，我们可以选择任何一个线段并将其长度精确地更改一个单位，无论是增加还是减少它，只要该线段在更改后保持正值即可。 

目标是将这三个长度转换为可以形成非退化三角形的三元组。 这意味着三个所得长度必须严格满足所有三角形不等式，因此每条边必须严格小于其他两条边的总和。 我们被要求提供此类单位变更所需的最少数量。 

每个操作都会对一个段产生±1的影响，因此我们付出的成本正是原始三元组和最终选择的三元组之间的总L1距离。 

每个值的约束最多为 10^6，因此任何尝试探索所有可能的最终三元组或逐步模拟更改的解决方案都是立即不可行的。 对状态的简单 BFS 或可能最终长度的强力枚举将涉及每个坐标数百万个数量级的搜索空间，这至少会变成 10^18 种组合，这是完全不可能的。 

一些边缘情况值得尽早隔离。 

如果这三个线段已经严格满足三角不等式，例如3、4、5，则答案为零。 尝试“无论如何调整”的粗心解决方案会错误地引入不必要的更改。 

如果两条边的总和已经等于第三条边，例如 1、2、3，则该形状是退化的。 必须严格打破平等，这意味着至少需要修改一个单元。 仅检查非严格不等式的解决方案会错误地认为这种情况有效。 

另一个微妙的情况是当一侧远大于其他两侧的总和时，例如 1, 1, 100。要以最佳方式解决此问题需要了解两个小边都可以增加或大边可以减少，并且如果没有结构，最佳策略并不明显。 

## 方法

 强力解释是考虑每个可能的最终正整数三元组，并计算将原始三元组转换为它的成本，同时检查它是否形成有效的三角形。 对于每个候选三元组，成本为 |a − a'| + |b − b'| + |c − c'|。 这在原则上是正确的，因为我们直接评估所有可达到的目标。 

问题在于规模。 每边可以从 1 移动到大约 max(a, b, c) 加上或减去极端情况下的不平衡，这已经为每个坐标产生了大约 10^6 种可能性。 总空间变成立方体，即使我们限制在合理的窗口内，候选者的数量仍然远远超出了时间上可以枚举的范围。 

关键的观察是，通过排序来看，三角形条件非常简单。 如果我们将最终边排序为 x ≤ y ≤ z，则条件变为 x + y > z。 这种不等式以一种有用的方式是单调的：如果一个三元组违反了它，唯一的解决方法是增加 x 或 y，或者减少 z，并且以单位步长这样做意味着成本与我们需要“缩小差距”z − (x + y) 的量呈线性关系。 

这表明我们不应该搜索所有三元组。 相反，我们尝试修复一个结构：我们将以这样的配置结束：两个数字不变或最小化调整，第三个数字调整得足以满足不等式。 由于成本与移动量呈线性关系，因此最佳解决方案始终对应于将系统推至边界 x + y = z + 1（满足严格不等式的最小整数），因为任何进一步的调整只会不必要地增加成本。

因此，问题归结为检查我们必须调整每条边多少，以确保排序后最大的边严格小于其他两条边的总和，并且在最便宜的方向上这样做。

 ## 算法演练

 ### 1.对三个长度进行排序

 我们对值重新排序，使得 a ≤ b ≤ c。 这隔离了唯一有意义的约束，即 c 与 a 和 b 相比是否太大。 排序确保我们不需要单独考虑多个三角形不等式排列。 

### 2.检查是否已经有效

 如果 a + b > c，则三元组已经形成严格的三角形。 不需要任何操作，所以答案是零。 此步骤抓住了这样一个事实：任何进一步的修改只会增加成本。 

### 3. 计算赤字

 如果 a + b ≤ c，则三角形条件失败。 故障量正是 c 超出允许最大值的程度。 我们定义一个间隙值：

 间隙 = c − (a + b) + 1

 这代表我们需要减少多少 c 或增加 a + b 才能使严格的不平等成为现实。 

+1 出现是因为我们需要 a + b 严格大于 c，而不是等于。 

### 4. 将差距转化为运营

 每个操作都会将一侧改变 1，因此 a + b − c 中的每一个改进单位都恰好对应于一次移动。 增加 a 或 b 会增加总和，减少 c 会减少阈值，并且两者的单位成本相同。 因此，最少的操作次数正是gap。 

### 5.输出结果

 根据三角形条件是否成立，返回 0 或间隙。 

### 为什么它有效

 排序后，三角形的可行性仅取决于单个线性不等式。 任何操作序列每次移动最多都会将表达式 a + b − c 更改为 1，并且每个有效的最终状态都要求此表达式至少为 1。因此，最小移动次数是将此表达式从其初始值推至 1 的最小成本，即 max(0, c − a − b + 1)。 没有其他的调整安排可以降低成本，因为每一步都为满足不平等贡献了一个单位的改进。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

a, b, c = map(int, input().split())
a, b, c = sorted([a, b, c])

if a + b > c:
    print(0)
else:
    print(c - a - b + 1)
```该解决方案首先读取三个段长度并对它们进行排序，以便隔离最大值。 这使我们能够将三角形条件简化为一次检查。 

条件直接测试严格的不等式是否已经成立。 如果是，则无需修改。 

否则，计算差值 c - (a + b) + 1。 该表达式是将系统带到三角形有效的边界所需的单位调整的确切数量。 不需要循环或模拟，因为每个操作都为满足不等式贡献了一个单位的改进。 

## 工作示例

 ### 示例 1：3 2 6

 排序后，我们有a = 2，b = 3，c = 6。 

| 步骤| 一个 | 乙| c | a + b | 状况 | 行动|
 | --- | --- | --- | --- | --- | --- | --- |
 | 初始化| 2 | 3 | 6 | 5 | 5≤6| 无效 |
 | 计算| - | - | - | - | 间隙 = 6 − 5 + 1 = 2 | 答案|

 差距是 2，这意味着我们需要改进两个单位。 一种可能的变换是从 6 减少到 5，然后从 2 增加到 3，达到满足三角形条件的 3,3,5。 

这个痕迹表明我们不需要推理要改变哪一边； 只有净失衡才重要。 

### 示例 2：13 111 57

 排序后，我们得到a = 13，b = 57，c = 111。 

| 步骤| 一个 | 乙| c | a + b | 状况 | 行动|
 | --- | --- | --- | --- | --- | --- | --- |
 | 初始化| 13 | 57 | 57 111 | 111 70 | 70 70 ≤ 111 | 无效 |
 | 计算| - | - | - | - | 间隙 = 111 − 70 + 1 = 42 | 答案|

 该算法表明，大的不平衡占主导地位，答案仅取决于最大的一边超过其他两者之和的程度。 

这些例子证实，只有排序的不等式很重要，而不是操作的具体分布。

## 测试用例```python
import sys, io

def solve():
    import sys
    a, b, c = map(int, sys.stdin.readline().split())
    a, b, c = sorted([a, b, c])
    if a + b > c:
        print(0)
    else:
        print(c - a - b + 1)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue().strip()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out

# provided samples
assert run("3 2 6") == "2"
assert run("250 100 200") == "0"
assert run("13 111 57") == "42"

# custom cases
assert run("1 1 2") == "1"
assert run("1 1 3") == "2"
assert run("5 5 5") == "0"
assert run("1 2 1000000") == "999998"

 ## 边缘情况

 对于输入 1 1 2，排序得到 1, 1, 2。较小的两个之和等于最大的，因此间隙为 2 − 2 + 1 = 1。算法输出 1，对应于任何单个单位的变化，例如将 2 减少到 1 或将其中一个增加到 2。 

对于 1 1 3，排序给出 1, 1, 3。间隙变为 3 − 2 + 1 = 2。该算法正确地识别出需要两次调整，因为单次移动无法恢复严格的不平等。 

对于 5 5 5，由于 5 + 5 > 5，不等式立即成立，因此算法返回 0，而不进入间隙计算分支。 这证实了当三角形已经存在时不会引入不必要的调整。
