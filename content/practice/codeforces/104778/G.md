 ## 解决方案
 ## 问题理解

 我们得到一串小写字母。 我们必须恰好删除 k 个位置，但有一个严格的规则：原始字符串中两个被删除的位置不能相邻。 删除这些字符后，剩余的字符保持顺序，并且字符串分成剩余字符的最大连续块。 

要求是每个这样的块必须与字符串相同。 如果只有一个块，则条件基本满足，因为没有任何东西可以与之比较。 

输出是一个简单的可行性检查：是否存在 k 个不相邻删除的选择，使所有结果块相等。 

n 高达 200000 的约束立即表明任何具有子串二次行为或详尽删除模拟的解决方案都是不可能的。 我们需要接近线性或线性算术的东西，可能涉及贪婪构造或具有结构约束的前缀匹配。 

一个关键的隐藏困难是删除不是任意分隔符：它们必须是不相邻的。 这将分割结构与路径图中独立集选择的组合耦合起来。 另一个微妙的点是，生成的块必须与字符串完全相等，而不仅仅是长度相等。 

一些边缘案例暴露了天真的推理失败的地方。 

如果 k 等于 0，则整个字符串是一个块，答案始终为“是”。 

如果k很大但在非邻接约束下仍然有效，则剩余字符的结构可能会迫使许多小块； 例如，周期字符串中的交替删除可以产生许多单字符片段，只有当其余字母都相等时，这些片段才基本相同。 

天真的想法的一个典型失败案例是假设我们只需要确保剩余的段具有相同的长度。 例如，考虑`s = "abacaba"`。 删除一个精心挑选的角色可以创建两个相同的片段`"aba"`，但仅等长分段并不能保证内容的平等。 

另一个微妙的失败是假设我们可以贪婪地强制执行周期性，而不考虑删除位置必须全局一致且不相邻。 

## 方法

 强力解释是选择 k 个不相邻的索引，模拟结果字符串，将其分割成块，并检查所有块是否相等。 在最坏的情况下，在长度为 n 的字符串中选择 k 个不相邻位置的方法数量已经是 k 的指数，因为它相当于在路径图中选择大小为 k 的独立集合。 即使我们有效地生成候选者，对于每个候选者，我们也必须重建字符串并比较段，导致每次检查至少 O(n)。 这很快就变得不可行。 

关键的观察是，一旦修复了删除，剩余的字符串必须由单个块的重复副本组成，并由删除的位置分隔开。 这意味着剩余的字符定义重复模式，而删除仅充当相同副本之间的分隔符。 

我们不考虑删除，而是颠倒视角：假设结果字符串由 t 个相同的块组成，每个块都是某个字符串 p。 然后通过在这些块内交错k个删除来形成原始字符串。 由于删除不能相邻，因此我们有效地分布分隔符，将字符串分成相等的连续的幸存字符段。 

一个关键的重新表述是将删除后的结果字符串视为可以分为 t 个相等的连续段的子序列。 令最终字符串长度为 m = n − k。 那么 m 必须能被 t 整除，并且每个线段的长度为 m / t。 每个段必须完全匹配，这意味着子序列具有周期为 m / t 的周期性结构。 

现在问题变成：我们能否选择一个长度为 m 的子序列，通过删除 k 个不相邻的字符而获得，使得它是具有一定周期长度的周期性子序列？ 

非邻接约束可以被重新解释为选择剩余字符之间的 k 个间隙，这意味着我们不能删除两个连续的原始位置，因此删除必须由至少一个保留的字符分隔。 这意味着在最终字符串中，在原始索引中的任意两个删除位置之间，至少有一个保留字符，这限制了删除的密集程度。 

解决方案最终是对可能的段计数进行建设性检查。 我们尝试 m 的所有除数 t（或等效地所有可能的块长度）。 对于每个候选，我们测试是否可以选择 k 个删除，以便剩余的字符串变得具有块大小 m / t 的周期性，同时遵守邻接约束。 检查可以简化为验证必须跨重复对齐的位置处的字符一致性，以及我们是否可以通过删除位置而不违反邻接性来“修复”不匹配。 

这将问题简化为对每个候选周期进行线性扫描的结构化贪婪可行性检查。

 | ---| ---| ---| ---|

 | 周期枚举+贪心验证 | O(n √n) | O(n √n) | O(n) | 已接受 |

 ## 算法演练

 我们首先确定最终长度 m = n − k。 如果 m 为非正数，我们仅在微不足道的情况下立即返回 YES，但在约束下 k ≤ (n+1)/2 确保 m 有效。 

然后，我们迭代所有可能数量的相等块 t，使得 m % t == 0。对于每个 t，块长度为 L = m / t。 

我们尝试验证是否可以形成长度为 m 的子序列，该子序列恰好是长度为 L 的字符串的 t 次重复，同时恰好删除 k 个字符并且从不删除相邻的原始索引。

我们模拟原始字符串的贪婪匹配过程。 我们维护一个指向长度为 L 的目标周期模式的指针。对于原始字符串中的每个字符，我们决定是将其保留为子序列的一部分还是将其删除。 

在每个位置 i，我们将 s[i] 与模式位置中的预期字符（构建的子序列对齐内的 i mod L）进行比较。 如果匹配，我们保留它并前进模式指针。 如果不匹配，我们考虑删除它，但前提是先前的原始位置未被删除，尊重邻接约束。 

我们跟踪使用了多少次删除。 如果在任何时候我们超过 k，我们就会停止这个候选者。 如果我们成功处理整个字符串并以恰好 k 个删除结​​束并且完全满足模式，则我们接受。 

我们对所有有效的 t 重复此操作。 

### 为什么它有效

 该算法是正确的，因为任何有效的解决方案都会在最终子序列上引入周期性结构。 一旦我们确定了块计数 t，每个保留位置必须对齐的结构就完全确定了。 剩下的唯一自由就是删除哪些不匹配的字符。 由于删除仅受邻接性约束，而不受全局交互的约束，因此可行性降低为局部贪婪决策过程：每当发生不匹配时，删除它是最优的，除非它违反邻接性，在这种情况下候选周期是不可能的。 这保证了如果给定 t 存在有效配置，则贪婪模拟将找到它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    m = n - k
    if m <= 0:
        print("YES")
        return

    # try all possible number of blocks t
    for t in range(1, m + 1):
        if m % t != 0:
            continue
        L = m // t

        deletions = 0
        last_deleted = False
        j = 0  # pointer in subsequence pattern

        ok = True

        for i in range(n):
            if j < m and s[i] == s[j % L]:
                j += 1
                last_deleted = False
            else:
                if last_deleted:
                    ok = False
                    break
                deletions += 1
                last_deleted = True
                if deletions > k:
                    ok = False
                    break

        if ok and j == m and deletions == k:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```该实现修复了候选周期结构，并贪婪地决定每个字符是否对最终子序列有贡献或必须被删除。 变量`j`跟踪有多少字符已被接受到子序列中，并且`j % L`强制重复候选块。 这`last_deleted`flag 通过防止两次连续删除来强制执行邻接约束。 

最终检查确保我们准确地构建了 m 个保留字符并准确地使用了 k 个删除。

 ## 边缘情况

 一种关键的边缘情况是最佳解决方案仅留下一个字符。 为了`n = 3, k = 2`，任何字符串都会变成单字符结果，因此算法必须将单块周期性视为有效。 贪婪模拟自然会处理这个问题，因为 L 变为 1 并且每个字符都与模式匹配。 

另一种情况是由于邻接约束而被迫隔离删除。 例如，在像这样的字符串中`abcdef`，尝试删除相邻的不匹配项将失败`last_deleted`检查，正确拒绝不可能的周期选择，即使字符频率表明可行性。 

当周期长度很大、接近 m 时，会出现进一步的边缘情况。 在这种情况下，模式退化为几乎完整的子序列，并且只有少量删除可用于修复不匹配。 当簇不匹配时，该算法会正确地失败这种情况，因为邻接限制会阻止消除连续错误。
