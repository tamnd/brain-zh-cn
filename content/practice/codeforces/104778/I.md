 ## 解决方案
 ## 问题理解

 我们有一个足球赛季，包括$n$匹配。 每场比赛都以三种结果之一结束：胜利、平局或失败。 一场胜利给予$k$分，平局得 1 分，负得 0 分。 我们还被告知所有累积的积分总数$n$匹配正是$p$。 

任务不是重建一个有效的赛季，而是确定可以产生给定总得分的最大可能平局次数。 如果胜、平、负的总和不超过$n$游戏可以准确产生$p$点，答案一定是$-1$。 

限制条件非常大：$n$可以达到$10^{12}$和$p$最多$10^{15}$，因此任何迭代匹配或尝试所有组合的方法都是不可能的。 该解决方案必须是纯粹的算术，并依赖于线性约束的结构推理。 

最微妙的情况是无法形成分数的边界情况。 例如，如果$p$太大（大于$nk$)，或者如果它不能表示为 1 和 的组合$k$，则不存在有效季节。 另一个微妙的情况是，最大化平局会迫使消耗太多比赛，从而无法获得足够的胜利来达到剩余分数。 

一个简单的不可能的例子是$n = 1, k = 5, p = 2$。 唯一可能的分数是 0、1 或 5，因此无法形成 2。 正确的输出是$-1$。 

另一个边缘情况是当所有比赛都是平局时，这会迫使$p = n$。 例如，$n = 10, p = 10, k = 3$有一个有效的解决方案，有 10 次平局，没有获胜。 

## 方法

 暴力方法会尝试枚举所有可能的胜利、平局和失败的分布。$n$匹配。 即使我们将其减少为迭代获胜和平局的次数，我们仍然会检查$O(n^2)$状态在最坏的情况下，因为每种获胜选择都会限制平局和失败。 这对于$n$最多$10^{12}$。 

关键的观察是，除了作为填充物之外，损失与得分无关。 问题简化为寻找非负整数$w$和$d$这样：$$wk + d = p$$和$$w + d \le n$$我们想要最大化$d$，这意味着最小化$w$，但仍然满足这两个约束。 

第一个约束纯粹是算术约束：$p - wk$必须为非负且等于$d$， 所以$p - wk \ge 0$和$p - wk$是一个整数。 

这将问题转化为选择有效的获胜次数$w$，每次胜利消耗$k$点，剩余的点必须恰好填满抽奖。 

为了最大化平局，我们希望尽可能最小$w$这样$p - wk \le n - w$，因为平局会消耗积分和比赛名额，而获胜则只消耗比赛名额。 

这导致对可能的情况进行直接可行性检查$w$，但自从$w \le n$和$w \le p/k$，我们只需要考虑一个小的结构化搜索：我们从获胜所需的最小数量开始$p$不超过剩余容量，并在模块化约束引起的小范围内进行调整。 

更具体地说，我们重写：$$d = p - wk$$和$$d \le n - w
\Rightarrow p - wk \le n - w
\Rightarrow p - n \le w(k - 1)$$这给出了下界$w$， 尽管$w \le \lfloor p/k \rfloor$给出一个上限。 自从$k \ge 2$，可行区域$w$是一个很小的区间，我们只需要测试边界周围恒定数量的候选者。 

我们选择最小的有效值$w$在此区间内，计算$d$，然后返回。

 ## 算法演练

 我们根据胜平局重新表述问题，然后将其简化为检查具有容量限制的线性丢番图约束的可行性。 

1. 计算最大可能获胜次数为$w_{\max} = \lfloor p / k \rfloor$。 这是不超过总积分的最大获胜次数。 
2.如果$w_{\max} > n$，将其减少到$n$，因为我们不能赢得比比赛更多的胜利。 这确保我们永远不会分配比现有更多的匹配项。 
3. 获胜次数固定$w$，剩余的点必须通过抽奖来填补：$$d = p - wk$$这是被迫的； 一次就没有自由$w$被选中。 
4. 检查可行性约束：

 使用的匹配数为$w + d$，所以我们要求：$$w + (p - wk) \le n$$简化为：$$p - w(k - 1) \le n$$5.自从增加$w$减少$d$，但也增加了匹配使用，我们搜索最小的$w$使得两个可行性条件都成立：$p - wk \ge 0$和$w + d \le n$。 
6.如果没有这样的$w$存在，返回$-1$。 
7. 否则计算$d = p - wk$对于所选择的$w$，并输出它。 

### 为什么它有效

 任何有效季节都对应一对$(w, d)$满足线性方程和线性容量约束。 分数方程修正$d$一次$w$选择，因此搜索空间折叠为单个维度。 可行性条件是单调的$w$：增加胜利会线性减少剩余积分，同时也会线性减少可用容量。 这种单调结构确保如果存在解，则首先满足约束的边界给出最大化绘制的最佳配置，因为任何较小的$w$将违反分数可行性和任何更大的$w$只会进一步减少平局。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, p, k = map(int, input().split())

    # If even all wins are not enough or too many points are impossible
    if p > n * k:
        print(-1)
        return

    # We try to minimize wins while still making score achievable with draws
    # From feasibility: p - w*k <= n - w  =>  p - n <= w*(k - 1)
    # Also: p - w*k >= 0

    w_min = max(0, (p - n + (k - 2)) // (k - 1))  # ceil((p - n)/(k - 1))
    w_max = min(n, p // k)

    if w_min > w_max:
        print(-1)
        return

    # Try boundary candidates (monotonic structure)
    best_d = -1

    for w in range(w_min, min(w_max, w_min + 5) + 1):
        d = p - w * k
        if d < 0:
            continue
        if w + d <= n:
            best_d = max(best_d, d)

    print(best_d if best_d >= 0 else -1)

if __name__ == "__main__":
    solve()
```该代码首先消除了即使最大胜利也无法达到分数的不可能情况。 然后，它从容量限制中得出获胜的下限，并从分数可行性中得出上限。 最后一步仅检查可行性转换边界附近的恒定大小窗口，因为约束在以下情况下表现单调：$w$。 

返回值是抽奖次数，计算公式为$p - wk$，一旦有效，它就直接跟随$w$是固定的。

 ## 边缘情况

 一种失败模式是假设每个分数低于以下值时都有解决方案$nk$。 例如，$n = 1, k = 5, p = 2$给出$p \le nk$，但没有组合产生 2。该算法拒绝它，因为$w_{\max} = 0$导致$d = 2$，这违反了$w + d \le n$。 

另一个边缘情况是最优解决方案需要零胜。 为了$n = 10, p = 10, k = 5$，最佳配置是10平0胜。 公式正确得出$w = 0$,$d = 10$，并且完全满足容量。 

第三种情况是当需要获胜以减少超出可用比赛的额外平局时。 为了$n = 5, p = 9, k = 2$，天真的贪婪可能会先尝试太多的抽牌，但约束力$w = 4, d = 1$，正好适合 5 场比赛。 该算法通过同时强制执行分数和容量约束来找到此边界，确保不会发生抽签的过度分配。
