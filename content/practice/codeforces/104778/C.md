 ## 解决方案
 ## 问题理解

 我们有两个长度相等的整数数组。 每个位置 i 定义一个“约束区间”，但该区间是无序的：索引 i 处的候选整数 x 的有效范围只是 ai 和 bi 之间的段，无论哪一个较大。 所以每一对在数轴上贡献一个闭区间。 

任务是计算有多少个整数 x 同时满足所有约束，这意味着 x 必须位于这 n 个区间的每一个区间内。 换句话说，我们正在寻找由 (ai, bi) 定义的所有线段的交集中的整数点数。 

约束很大，n 高达 200000，值高达 1e9。 这排除了尝试所有可能的 x 或显式构造范围的任何方法。 由于范围太大，无法对值域进行全面扫描。 唯一可行的方向是将问题压缩到每个间隔的恒定信息量。 

一个幼稚的错误是尝试通过逐一检查每个区间并过滤候选值来构建一组全局的有效 x 值。 即使从单个区间开始，迭代相交的集合也会爆炸，因为当范围很大时，许多大整数区间的交集无法明确表示为一组单独的点。 

第二个微妙的陷阱是忘记每一对都没有定义方向，因此 (ai, bi) 和 (bi, ai) 是相同的约束。 将它们视为有向间隔会导致不正确的交叉边界。 

## 方法

 如果我们尝试暴力破解，我们可以想象迭代从 1 到 1e9 的每个整数 x 并检查它是否满足所有 n 个区间。 每次检查的成本为 O(n)，因此最坏的情况是 O(1e9 * n)，这是完全不可行的。 

关键的观察是每个约束都是一个标准闭区间。 所有有效 x 的集合正是这些区间的交集。 一条线上多个区间的交集也是单个区间，可能为空。 这意味着我们不需要跟踪许多候选者，我们只需要全局重叠。 

每个区间 [min(ai, bi), max(ai, bi)] 贡献一个下限和一个上限。 所有区间的交集是通过取所有下界的最大值和所有上限的最小值来获得的。 如果结果左端点大于右端点，则交集为空。 否则，它们之间的每个整数都是有效的，我们直接对它们进行计数。 

这减少了从管理 n 个间隔到维护两个运行值的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n·1e9) | O(n·1e9) | O(1) | O(1) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们在扫描输入一次的同时维护所有间隔的交集。

1. 对于每一对 (ai, bi)，将其转换为适当的区间 [l, r]，其中 l = min(ai, bi) 且 r = max(ai, bi)。 此标准化步骤是必要的，因为端点是无序的。 
2. 将全局交集初始化为包含所有整数的区间：左界非常小，右界非常大。 这确保第一个间隔完全定义初始限制。 
3. 对于每个区间 [l, r]，通过将新的左边界设置为 max(current_left, l) 来更新交集。 这仅保留迄今为止看到的每个间隔中有效的值。 
4. 同样，将右界更新为 min(current_right, r)。 这确保我们丢弃超出任何约束的值。 
5. 处理完所有区间后，检查结果左边界是否大于右边界。 如果是这样，则没有整数满足所有约束。 
6. 否则，答案是右−左+1，因为这个闭区间中的每个整数都是有效的。 

### 为什么它有效

 每个间隔定义一组允许的整数。 由直线上的区间定义的集合的交集本身就是一个区间。 在每一步中，维护的范围恰好等于迄今为止处理的所有间隔的交集。 更新保留了这一属性，因为新区间之外的任何整数都必须违反至少一个约束，而前一个交集和新区间内的任何整数都满足迄今为止看到的所有约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    left = -10**18
    right = 10**18
    
    for i in range(n):
        l = min(a[i], b[i])
        r = max(a[i], b[i])
        left = max(left, l)
        right = min(right, r)
    
    if left > right:
        print(0)
    else:
        print(right - left + 1)

if __name__ == "__main__":
    solve()
```实现直接反映了算法。 唯一微妙的设计选择是为初始交叉点边界使用足够大的哨兵。 由于输入值最大为 1e9，因此使用 ±1e18 可以安全地避免首次更新之前的意外削波。 其余的逻辑是一个简单的滚动交叉点。 

## 工作示例

 ### 示例 1

 输入：

 n = 4

 a = [5, 5, 5, 5]

 b = [5, 5, 5, 5]

 每个区间都是 [5, 5]，因此交集始终保持 [5, 5]。 

| 步骤| 间隔 | 左| 对|
 | --- | --- | --- | --- |
 | 1 | [5, 5] | 5 | 5 |
 | 2 | [5, 5] | 5 | 5 |
 | 3 | [5, 5] | 5 | 5 |
 | 4 | [5, 5] | 5 | 5 |

 答案是 1。这证实了算法正确处理退化区间。 

### 示例 2

 输入：

 n = 3

 a = [3, 7, 10]

 b = [6, 8, 12]

 区间为 [3,6]、[7,8]、[10,12]。 这些不重叠。 

| 步骤| 间隔 | 左| 对|
 | --- | --- | --- | --- |
 | 1 | [3,6]| 3 | 6 |
 | 2 | [7,8]| 7 | 6 |
 | 3 | [10,12]| 10 | 10 6 |

 步骤2之后，左>右，因此交集变为空并保持为空。 

答案是 0。这表明可行性的早期崩溃。

 ## 边缘情况

 一种边缘情况是所有间隔都是相同的单点。 对于重复输入 n = 3 且 (ai, bi) = (5, 5) 的情况，算法在第一次迭代后设置 left = 5 和 right = 5，并保持不变。 输出变为 1，正确计数只有 x = 5 满足所有约束。 

另一个边缘情况是间隔在前几步之后立即崩溃。 例如：

 输入：

 n = 2

 a = [1, 100]

 b = [2, 90]

 标准化后我们得到 [1,2] 和 [90,100]。 处理第一个间隔后，左 = 1，右 = 2。第二个间隔后，左变为 90，右变为 2，产生左 > 右并输出 0。一旦交集变空，算法就会正确检测到不可能性，即使以后的更新始终如一地继续。
