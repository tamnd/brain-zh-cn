 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，它通过单字符翻转随时间变化。 除了这些更新之外，我们还反复被问到有关任何子字符串的结构问题：需要为其字符分配多少种颜色，以便每个颜色类在按原始顺序读取时形成一个没有两个相等相邻位的字符串。 

换句话说，我们想要将子字符串的索引分成组（颜色）。 如果我们取任意一组并按原始顺序读取子字符串的字符，则生成的序列必须严格在 0 和 1 之间交替。因此，单一颜色的行为就像一条链，在投影后不能包含两个相等的连续位。 

对于每个查询子字符串，我们必须找到覆盖它所需的此类交替链的最小数量。 字符串是动态的，因此必须支持点翻转和范围查询。 

约束很大，最多 4 · 10^5 个字符和 2 · 10^5 个操作。 任何在整个范围内重新计算每个查询信息的解决方案都将超出限制。 在最坏的情况下，即使每个查询的 O(n) 也会导致大约 8 · 10^10 次操作，这是不可能的。 这立即强制形成支持对数或摊销更新和查询的结构。 

当子串已经交替时，就会出现微妙的边缘情况。 例如，对于 s = 01010，答案必须为 1。天真的解释可能会错误地认为由于定义而始终需要多种颜色，但单一颜色可以轻松满足条件。 另一个边缘情况是像 00000 这样的常量子串，其中每一对都是相同的，迫使每个元素进入不同的交替链，给出等于长度的答案。 任何正确的解决方案都必须在这些极端值之间正确插值。 

## 方法

 我们首先考虑直接构建的观点。 修复一个子串。 我们希望为每个位置分配一种颜色，以便在每种颜色中不会出现相同的相邻值。 这相当于保证每当两个相同的位以相同的颜色出现时，它们之间必须至少有一个按原始顺序相反的位。 

一个蛮力的想法是从左到右处理子字符串，并贪婪地将每个位置分配给不违反交替约束的第一个有效颜色。 为了检查有效性，我们必须跟踪每种颜色最后分配的位。 每个字符可能需要扫描所有现有颜色。 在最坏的情况下，例如一串相同的位，我们将为每个位置创建一个新的颜色，并且每次插入可能会扫描所有先前的颜色，从而在最坏的情况下导致每个查询的 O(n^2) 行为。 

关键的观察结果是，答案仅取决于当我们将子字符串压缩为最大相等段时二进制值变化的次数。 每个段都是一系列相同的位。 在一个运行中，所有字符都是相同的，因此任何两个字符都不能共享颜色，除非它们被相同颜色序列中相反的运行分隔开。 这创建了相当于覆盖运行之间的转换的约束。 

每次值从 0 翻转到 1 或 1 翻转到 0 时，我们都会引入一个“边界”，以防止在不增加重叠的情况下跨相邻运行重复使用颜色。 最佳颜色数量是此类游程边界数量的一半。 直观上，每种颜色最多可以以保留交替的方式覆盖两次运行过渡，因此我们需要足够的颜色来成对覆盖所有过渡。 

因此，问题简化为在翻转下动态维护运行结构，并回答对于任何范围，存在多少个相邻的相等对或转换。 这样我们就可以计算运行计数，并从中得出答案。

为了有效地支持更新和范围查询，我们维护一个段树，为每个段存储其第一个和最后一个值以及其中的转换数量。 合并两个段时，我们会添加转换计数，并在它们之间的边界引入额外更改或合并两个运行时进行调整。 

这使我们能够以 O(log n) 的时间计算任意子串中的运行次数，从而计算转换次数。 答案变成了运行计数的简单算术函数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每个查询 O(n^2) | O(1) | O(1) | 太慢了|
 | 线段树溢出 | 每次查询/更新 O(log n) | O(n) | 已接受 |

 ## 算法演练

 我们将字符串视为相等字符的运行序列，但我们将其隐式维护在线段树中，因此更新不需要全局重建运行。 

1. 构建一个线段树，其中每个节点存储线段内的第一个字符、最后一个字符以及转换数。 转换是指该段内的位置 i，使得 s[i] != s[i+1]。 
2. 对于叶节点，初始化很简单：first = last = s[i]，并且transitions = 0。这对长度为1 的单个游程进行编码。 
3. 合并两个子项时，我们将它们的转换计数相加。 如果左孩子的最后一个字符与右孩子的第一个字符不同，我们会添加一个额外的转换。 此步骤正确地考虑了穿过中间的运行边界。 
4. 对于每个更新查询，我们翻转单个字符并更新相应的叶子，然后向上重新计算值。 每次重新计算仅取决于子级，因此需要对数时间。 
5. 对于每个范围查询，我们查询线段树以检索 [l, r] 的合并节点，这给出了该子字符串中的转换总数。 
6. 将转换转换为运行计数，即运行 = 转换 + 1，因为每个转换都会将运行数增加 1。 
7. 将答案计算为 (runs + 1) // 2，这反映了需要多少个交替颜色链来覆盖所有运行而不违反每个颜色类内的交替。 

### 为什么它有效

 在任何颜色类中，提取的序列必须交替，因此两个相等的位不能按提取的顺序连续出现。 原始子串中的每次运行都会强制跨运行的颜色分配之间的分离约束。 单一颜色最多可以安全地“跳过”一个边界而不违反交替，但不能跳过两个连续的边界而不造成冲突。 这限制了单一颜色覆盖运行结构的效率。 线段树在合并时正确地保留了游程结构，并且从转换到游程的转换保留了计算最小数量的交替链所需的所有信息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("lch", "rch", "first", "last", "trans")
    def __init__(self, first=0, last=0, trans=0):
        self.lch = None
        self.rch = None
        self.first = first
        self.last = last
        self.trans = trans

def merge(a, b):
    if a is None:
        return b
    if b is None:
        return a
    res = Node()
    res.first = a.first
    res.last = b.last
    res.trans = a.trans + b.trans + (1 if a.last != b.first else 0)
    return res

class SegTree:
    def __init__(self, s):
        self.n = len(s)
        self.s = s
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.tree = [Node(0, 0, 0) for _ in range(2 * self.size)]
        self.build()

    def build(self):
        for i in range(self.n):
            v = int(self.s[i])
            self.tree[self.size + i] = Node(v, v, 0)
        for i in range(self.size - 1, 0, -1):
            self.tree[i] = merge(self.tree[2 * i], self.tree[2 * i + 1])

    def update(self, idx):
        i = self.size + idx
        v = 1 - self.tree[i].first
        self.tree[i] = Node(v, v, 0)
        i //= 2
        while i:
            self.tree[i] = merge(self.tree[2 * i], self.tree[2 * i + 1])
            i //= 2

    def query(self, l, r):
        l += self.size
        r += self.size
        left_res = None
        right_res = None
        while l <= r:
            if l % 2 == 1:
                left_res = merge(left_res, self.tree[l])
                l += 1
            if r % 2 == 0:
                right_res = merge(self.tree[r], right_res)
                r -= 1
            l //= 2
            r //= 2
        return merge(left_res, right_res)

def solve():
    n = int(input())
    s = list(input().strip())
    q = int(input())

    st = SegTree(s)

    out = []
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            i = int(tmp[1]) - 1
            s[i] = '1' if s[i] == '0' else '0'
            st.update(i)
        else:
            l = int(tmp[1]) - 1
            r = int(tmp[2]) - 1
            res = st.query(l, r)
            transitions = res.trans
            runs = transitions + 1
            ans = (runs + 1) // 2
            out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```线段树准确地存储了跨串联保留运行结构所需的三部分信息。 更新操作翻转单个叶子并仅重建受影响的路径。 查询返回一个表示子字符串的完全合并节点，其中的转换将转换为运行，然后转换为最终答案。 该公式仅在聚合后应用，避免任何按位置模拟。 

一个常见的陷阱是尝试直接在更新下维护运行计数而不存储边界字符。 如果没有第一个/最后一个信息，合并两个段会在边界处失去正确性，因为新的转换可能会出现或消失，具体取决于端点相等性。

 ## 边缘情况

 单字符子字符串始终具有零次转换和一次运行。 线段树返回 trans = 0，runs = 1，公式给出 (1 + 1) // 2 = 1，这与一种颜色通常满足交替的事实相匹配。 

对于像 000000 这样的常量子字符串，每次合并都会保持first = last = 0 并累积零内部转换。 整个段上的每个扩展仍然是一次运行，产生答案 (6 + 1) // 2 = 3。这符合分隔相同块的需要，以便没有颜色类创建非交替投影。 

对于像 010101 这样的完全交替的子串，转换等于 n - 1 并且运行等于 n。 该公式大致得出 n / 2 + 1，反映出即使原始字符串完美交替，每个颜色类也只能在有限的运行结构中安全地交织，而不会违反其提取序列中的邻接约束。
