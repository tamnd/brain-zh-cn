 ## 解决方案
 ## 问题理解

 我们得到一个简单的无向图，最多有 2000 个顶点，由其邻接矩阵表示。 从这张图中，我们必须恰好选择 k 个不同的顶点。 选择它们后，我们删除这些顶点并用一个新顶点 V 替换它们。V 的邻接由交集定义：仅当每个选定的顶点最初都连接到 x 时，V 才连接到剩余的顶点 x。 

换句话说，V 仅保留所有选定顶点共有的边。 任务是决定我们是否可以选择 k 个顶点，使得这个合并的顶点 V 连接到每个未被删除的顶点。 如果存在这样的选择，我们必须输出任何有效的 k 个顶点集，否则输出 -1。 

关键约束是 n ≤ 2000，它允许大约 O(n^2) 或 O(n^2 log n) 解决方案，但根据常数使任何 O(n^3) 或更差的方法处于边界状态。 由于输入本身是一个 n × n 矩阵，读取它的成本已经是 O(n^2)，因此理想情况下，解决方案应该接近该规模。 

当所选集合之外的某些顶点缺少连到一个选定顶点的边时，就会出现一种微妙的失败情况。 该单个缺失边消除了最终邻接中包含该顶点的所有候选集。 例如，如果我们选择邻域略有不同的顶点，它们的交集会迅速缩小，并且可能变得不通用，即使每个顶点单独高度连接。 

另一个边缘情况是 k 很大，特别是接近 n 时。 如果 k = n − 1，那么我们本质上是在问是否存在一个顶点，其与所有其他顶点的邻域交集是完全的，这是非常严格的，并且迫使仔细的全局推理而不是局部启发式推理。 

## 方法

 直接的暴力策略是尝试 k 个顶点的每个子集，并检查它们的公共邻域是否包含所有剩余的顶点。 对于每个子集，我们将与邻接集相交，每个顶点的成本为 O(n)，因此单次检查的时间复杂度为 O(k·n)。 子集的数量是二项式 n 选择 k，在最坏的情况下是指数的，即使 n = 50 也立即不可行。 

关键的观察结果是，条件是全局的，但可以在所选集合之外的每个顶点本地重写。 修复未选择的顶点 u。 为了使 V 连接到 u，每个选定的顶点都必须连接到 u。 这意味着所选集合必须完全包含在与 u 相邻的顶点集合内。 因此，每个外部顶点都会施加一个约束：所有选定的顶点必须位于其邻接集中。 

因此，如果 u 在压缩后保持连接，每个顶点 u 都定义了一组允许的候选点 S(u)。 对于所有未选择的 u，我们需要一个位于每个 S(u) 内部的大小为 k 的集合。 这相当于选择避免违反太多约束的k个顶点，或者更直接地，我们可以以补集形式重新解释它。 

我们没有根据允许的集合进行推理，而是翻转了观点。 仅当顶点 v 连接到所选集合之外的每个顶点时，该顶点 v 才能包含在所选集合中。 这很难直接测试，但我们可以利用对称性：如果顶点 v 没有连接到某个 u，那么如果选择 v，u 就不能在最终剩余的集合中。 这创建了一种互斥结构。 

更有效的重新表述是查看补图。 在补图中，边代表禁止对。 “所有选定的顶点必须连接到每个剩余顶点”的条件转化为所选集合与剩余顶点没有“不良交互”，这最终简化为可行性条件，可以通过从与不断增长的约束集相互一致的顶点贪婪地构建候选集来检查。

解决此问题的标准方法是维护一组候选顶点，这些顶点仍可能是解决方案的一部分。 我们迭代地强制由集合外部的顶点引起的约束，每当我们检测到不兼容时就会缩小候选池。 如果最后我们可以从剩余的一致池中提取 k 个顶点，那么答案就存在。 

这是可行的，因为每个约束在邻接矩阵条目级别都是二元的，因此可以通过同时维护所有顶点的一致性而不是枚举子集来验证可行性。

 | 对候选人的约束过滤| O(n^2) | O(n^2) | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 我们以一种允许我们维护一组仍然是可行候选者的顶点的方式来解释该条件。 

1. 从所有顶点作为潜在候选点开始。 我们将逐步消除无法参与任何大小为 k 的有效解的顶点。 
2.对于每个顶点u，计算其邻接位掩码或邻接集。 这使我们可以快速测试与其他顶点的兼容性条件。 
3. 对于每个顶点 u，我们检查有多少个顶点与 u 不相邻。 如果有太多非邻居，那么 u 就不能属于任何有效的解决方案，除非我们被允许从最终剩余集合中排除所有这些非邻居。 由于我们必须将 n−k 个顶点保留在所选集合之外，因此这就施加了一个约束：只有当顶点 u 在兼容配置的图中最多有 n−k 个非邻居时，该顶点 u 才可以安全地包含在内。 
4.我们维护一个初始化为所有顶点的候选集C。 对于每个顶点 u，我们计算 C 中有多少个顶点未与 u 连接。 如果这个数字超过 n − k，则 u 不能成为任何有效选择的一部分，并从 C 中删除。这是因为太多的冲突会迫使太多的顶点位于所选集合之外，从而为所需的结构留下足够的空间。 
5.处理完所有顶点后，如果候选集C的顶点少于k个，则不存在解，输出-1。 
6. 否则，我们从 C 中选择任意 k 个顶点并输出它们。 

关键的微妙之处在于我们永远不需要显式地构造最终的补集； 我们只确保每个选定的顶点仍然可以与剩余顶点的足够大的一致结构共存。 这完全避免了指数子集枚举。 

### 为什么它有效

 不变的是，从 C 中删除的每个顶点都被证明与成为任何有效的大小 k 选择的一部分不兼容。 删除条件确保包含这样的顶点将强制从剩余图中排除超过 n-k 个顶点，这与精确删除 k 个顶点同时仍保留完全兼容的结构的要求相矛盾。 因此，C 始终包含所有潜在的有效顶点，并且 C 的任何 k 子集都遵守合并顶点 V 连接到每个剩余顶点所需的所有邻接约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    g = [list(map(int, input().split())) for _ in range(n)]

    # C = all candidates
    cand = list(range(n))

    # Precompute non-neighbors for each vertex
    non_adj = []
    for i in range(n):
        bad = []
        for j in range(n):
            if i != j and g[i][j] == 0:
                bad.append(j)
        non_adj.append(bad)

    allowed = [True] * n

    for u in range(n):
        cnt = 0
        for v in range(n):
            if allowed[v] and g[u][v] == 0:
                cnt += 1

        # if too many conflicts, u cannot be in solution
        if cnt > n - k:
            allowed[u] = False

    cand = [i + 1 for i in range(n) if allowed[i]]

    if len(cand) < k:
        print(-1)
    else:
        print(*cand[:k])

if __name__ == "__main__":
    solve()
```该代码首先读取邻接矩阵并构造一个布尔兼容性过滤器。 它不是明确地构建邻域的交集，而是为每个顶点计算有多少不兼容的顶点仍然可行。 如果一个顶点与当前允许的 n − k 个以上的顶点冲突，则它不能成为任何有效构造的一部分并被丢弃。 

最后一步只是检查是否有足够的顶点在修剪中幸存下来。 如果是，则它们中的任何 k 都是有效的，因为所有剩余的顶点都与压缩操作引起的所需约束结构成对一致。

 ## 边缘情况

 几乎每一对都连接的密集图仍然需要仔细计算非邻居。 该算法对称地处理所有顶点，因此即使在完整图中，每个顶点仍然是允许的，并且任何 k 子集都是有效的。 

在完全空的图中，每个顶点都有最大冲突计数。 对于 k < n，每个顶点看到 n − 1 个非邻居，超过 n − k，因此所有顶点都被消除，输出正确为 -1。 

当 k 接近 n 时，例如 k = n − 1，阈值 n − k 为 1，因此即使有两条缺失边的顶点也会变得无效。 该算法正确地变得足够严格，可以拒绝几乎所有顶点，除非图几乎完整，符合压缩操作所施加的结构要求。
