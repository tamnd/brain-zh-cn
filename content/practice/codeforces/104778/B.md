 ## 解决方案
 ## 问题理解

 我们给出了成功投篮的一系列距离。 每次射击都会根据阈值贡献分数`d`我们选择的。 如果射击距离严格小于`d`，该投篮值 2 分。 否则，如果距离大于或等于`d`，该投篮得 3 分。 

我们的任务是选择一个非负整数`d`这样所有镜头的总得分就变成了`k`。 在所有有效选择中`d`，我们需要最小的一个。 

这里重要的结构是改变`d`只影响每个距离落入阈值的哪一侧。 增加`d`将一些投篮从三分球组转移到两分球组，并减少`d`则相反。 

约束足够小，可以根据候选阈值进行直接模拟。 和`n ≤ 1000`，即使是 O(n^2) 或 O(n log n) 方法在 1 秒限制下也足够快。 这立即表明我们有能力测试多个候选值`d`，特别是当我们利用排序或离散断点时。 

一个关键的观察结果是，只有`d`等于一些`ai`或者位于两个连续排序的距离之间可以改变镜头的分配。 这将所有整数的无限搜索空间减少到最多`n + 1`有意义的案例。 

出现微妙的边缘情况时`d = 0`。 既然所有`ai ≥ 1`，每一个镜头都会变成`ai ≥ d`，所以每次投篮贡献 3 分。 这通常会成为可能的最高分数`3n`，并且它是我们必须明确包含的有效候选者。 

另一个边缘情况是当期望的分数`k`等于`2n`，这意味着每次投篮都必须在 2 分球组中。 这只能发生在`d`严格大于所有距离。 

## 方法

 简单的方法是尝试每个整数值`d`从 0 到一个大的上限，计算每个分数的分数，然后选择最小的有效分数。 对于每个`d`，我们扫描所有`n`距离并决定每个贡献 2 分还是 3 分。 每张支票的成本为 O(n)。 由于距离可达 10^9，因此安全上限为`d`也可能在 10^9 左右，这使得这种方法在最坏的情况下太慢，需要大约 10^12 次操作。 

关键的见解是得分函数仅在以下情况下发生变化：`d`穿过数组中的距离之一。 在两个连续排序值之间，元素集`< d`和`≥ d`保持不变，所以分数是恒定的。 这意味着我们只需要考虑`d`在从输入值导出的有限集中，通常所有不同的距离加 0。 

一旦我们对数组进行排序，我们就可以通过维护有多少元素低于阈值来模拟每个候选阈值的分数`d`。 作为`d`增加，该计数单调增加，并且分数的变化可预测。

 ## 算法演练

 1. 按非降序对距离数组进行排序。 排序很有用，因为它允许我们推断有多少元素低于阈值`d`一旦我们确定了位置，时间复杂度为 O(1)。 
2. 通过迭代有多少元素被分配给“3点组”（那些具有`ai ≥ d`）。 我们不直接计算前缀和，而是跟踪分割点`i`，其中元素来自`i`到`n-1`贡献3分，其余贡献2分。 
3.对于每个可能的分割索引`i`从 0 到`n`，将其解释为选择`d`之间`a[i-1]`和`a[i]`（带有边界处理）。 后缀中的所有元素`[i, n)`≥ d 并贡献 3 分，而前缀`[0, i)`贡献2分。 
4. 计算本次分组的得分为`2 * i + 3 * (n - i)`。 该公式直接编码评分规则，无需单独模拟每个镜头。 
5. 检查这个分数是否等于`k`。 如果是，则计算最小的`d`从而实现了这种分裂。 最小有效值`d`是 0 （对于`i = 0`） 或者`a[i-1] + 1`什么时候`i > 0`。 
6. 记录此类最小值`d`跨越所有有效的分割。 

正确性取决于以下事实：每个有效阈值完全对应于已排序数组的一个分区`< d`和`≥ d`，并且每个这样的分区都可以由某个区间表示`d`价值观。 

### 为什么它有效

 该算法将无限组可能的阈值压缩为最多`n + 1`由距离排序顺序定义的等价类。 在每个类中，元素的顺序相对于`d`不会改变，因此得分函数保持不变。 因此，详尽地枚举所有分割位置涵盖了所有可能的不同结果，并选择最小的`d`每个有效结果确保我们找到全局最小的得分阈值`k`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))
a.sort()

best = None

for i in range(n + 1):
    score = 2 * i + 3 * (n - i)
    if score == k:
        if i == 0:
            d = 0
        else:
            d = a[i - 1] + 1
        if best is None or d < best:
            best = d

print(best)
```该解决方案首先对距离进行排序，以便每个阈值对应于连续的前缀后缀分割。 循环结束`i`代表选择下面有多少个元素`d`。 评分公式直接评估两组的贡献，无需逐项检查。 

施工时`d`，边界的选择至关重要。 如果我们想要确切地`i`元素严格小于`d`， 然后`d`必须大于`i-1`第 - 个元素且至多`a[i]`。 选择`a[i-1] + 1`是强制这种分离的最小整数。

最小的`d`实现这一目标的是`a[1] + 1 = 21`。 

这与所需的分数完全匹配，确认基于分割的解释正确地将阈值映射到结果。

 ## 边缘情况

 当所有投篮必须贡献 3 分时，得分为`3n`，对应于`i = 0`。 在这种情况下，算法正确分配`d = 0`。 例如，使用输入`n = 3`,`a = [5, 10, 20]`,`k = 9`，循环发现`i = 0`有效并返回`0`，匹配以下事实：每个`ai ≥ 0`。 

当所有投篮必须贡献2分时，得分为`2n`，对应于`i = n`。 为了`a = [2, 4, 6]`,`k = 6`，有效的分割是`i = 3`。 该算法分配`d = a[2] + 1 = 7`，这是确保所有元素严格低于的最小阈值`d`。 

当答案位于两个相邻值之间时，例如`a = [3, 8, 10]`我们需要下面的两个元素`d`，算法选择`i = 2`和集`d = a[1] + 1 = 9`。 这保证了`3, 8 < 9`和`10 ≥ 9`，毫无歧义地保留预期的分割。
