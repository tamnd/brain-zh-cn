 ## 解决方案
 ## 问题理解

 我们在数轴上得到一组点。 我们可以在整数线上的任何位置放置一个附加点，包括负数位置。 对于这个选定的点$x$，我们计算绝对距离的总和$x$到所有现有点。 任务是判断是否存在整数坐标$x$使得该总和等于给定的目标值$d$，如果是，则输出任何此类坐标。 

这里的关键对象是整数函数：$$F(x) = \sum_{i=1}^{n} |x - a_i|$$我们需要找到任意整数$x$这样$F(x) = d$。 

约束条件很大：最多 200,000 个点，坐标最多$10^{12}$， 尽管$d$可以大到$10^{17}$。 这立即排除了任何独立评估每个候选人职位总和的方法。 直接扫描最小和最大输入值之间的所有整数坐标已经是不可行的，因为该范围可达$10^{12}$，并评估每个职位的成本$O(n)$。 

第二个微妙的困难是该函数不是任意的：它是凸且分段线性的，斜率仅在给定点发生变化。 这种结构是问题得以解决的唯一原因。 

边缘情况主要以三种形式出现。 

一种情况是所有点都相同。 例如，如果所有$a_i = 100$， 然后$F(x) = n \cdot |x - 100|$。 如果$d = 0$， 仅有的$x = 100$作品。 如果$d > 0$，我们必须检查是否$d$可以整除$n$，否则不存在整数解。 

另一种情况是当$n = 1$。 然后$F(x) = |x - a_1|$，任何解决方案都是简单的$x = a_1 \pm d$。 基于中位数属性的天真的推理在这里可能会失败，因为基于中位数的直觉退化了。 

第三种情况是当期望值低于最小可能总和时。 该函数在任何中位数处都达到最小值，并且该最小值可能已经超过$d$。 在这种情况下，无论我们如何离开，都不存在任何解决方案。 

## 方法

 一个蛮力的想法是尝试给定点的最小和最大坐标之间的每个整数位置，并计算每个位置的距离总和。 这是可行的，因为该函数在任何地方都定义良好，但速度太慢。 坐标范围最大可达$10^{12}$，以及每次评估成本$O(n)$，导致大约$10^{17}$最坏情况下的操作。 

关键的结构观察是$F(x)$是整数上的凸函数。 它的斜率仅在输入点处变化，并且在连续点之间它是线性的。 这意味着我们不需要任意搜索； 相反，我们可以使用前缀计数和前缀和来分析该函数。 

一旦点被排序，我们就可以计算$F(x)$在给定的情况下有效地$x$使用二分查找。 更重要的是，由于该函数是凸且分段线性的，因此它会减小直到中值区域，然后单调增加。 这个结构允许我们确定目标值是否$d$位于最小值的左侧或右侧，然后反转该侧的线性表达式。 

核心思想是计算中位数的最小值，并将其与$d$，然后使用前缀和求解函数递增侧的线性方程。

 ## 算法演练

 ### 最优推理

 1. 对坐标数组进行排序。 排序至关重要，因为绝对值的结构取决于排序。 
2. 计算已排序数组的前缀和。 这样可以快速评估候选位置每一侧有多少点。 
3.找到中间位置$m$。 任何中位数都会使函数最小化$F(x)$。 我们计算最小值$F(m)$。 
4. 如果$d < F(m)$，停止并输出NO。 该函数在线任何地方都不能低于其最小值。 
5. 如果$d = F(m)$，输出中值坐标本身。 任何中位数都有效，选择一个就足够了。 
6. 否则，我们有$d > F(m)$。 解必须位于中值区域之外，无论是向左还是向右。 我们独立检查两个方向。 
7. 对于固定边，表示$F(x)$作为使用前缀和的线性函数。 在数组的右侧，函数的斜率等于点数，并且值可预测地增加。 我们解决$x$使得线性表达式等于$d$。 
8. 验证候选人$x$如果需要，可以直接替换，如果有效则输出。 

### 为什么它有效

 功能$F(x)$是凸的，因为每一项$|x - a_i|$是凸的，并且求和保持凸性。 凸整数函数具有单个全局最小区间（中值区域），并且在远离它的两侧单调非递减。 这保证了沿着一个或两个单调分支可以精确地达到高于最小值的任何值，并且可以通过反转该分支上的线性表达式来求解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    def cost(x):
        import bisect
        k = bisect.bisect_right(a, x)
        left = x * k - pref[k]
        right = (pref[n] - pref[k]) - x * (n - k)
        return left + right

    m = a[n // 2]
    base = cost(m)

    if d < base:
        print("NO")
        return

    if d == base:
        print("YES")
        print(m)
        return

    # try right side
    total = n
    sum_all = pref[n]

    # candidate on right: x >= m
    # F(x) = sum(x - a_i for a_i <= x) + sum(a_i - x for a_i > x)
    # we binary search x by monotonicity
    lo, hi = m, 10**18

    ans = None
    for _ in range(200):
        mid = (lo + hi) // 2
        if cost(mid) < d:
            lo = mid
        else:
            hi = mid

    if cost(lo) == d:
        ans = lo

    if ans is None:
        lo, hi = -10**18, m
        for _ in range(200):
            mid = (lo + hi) // 2
            if cost(mid) < d:
                hi = mid
            else:
                lo = mid
        if cost(lo) == d:
            ans = lo

    if ans is None:
        print("NO")
    else:
        print("YES")
        print(ans)

if __name__ == "__main__":
    solve()
```该实现依赖于直接评估函数$F(x)$使用前缀和和二分搜索将点分成左右两部分$x$。 成本函数是核心原语，运行在$O(\log n)$由于其中的二分搜索。 

我们首先计算基于中值的最小值。 该值立即决定可行性。 之后，我们利用单调性：当我们从中位数向右移动时，成本严格增加，因此我们可以二分搜索成本匹配的点$d$。 同样的逻辑对称地适用于左侧。 

一个常见的陷阱是假设封闭式反演总是更简单。 虽然可能，但正确处理整数边界比依赖凸函数的单调二分搜索更脆弱。

```排序后的数组是`[1, 4]`，中位数是`4`。 

| 步骤| x| 成本(x) |

这显示了基于凸最小值的关键可行性检查。

 ## 边缘情况

 对于单点情况，输入：```
1 5
10
```功能很简单$F(x) = |x - 10|$。 该算法计算中位数为 10，找到基本成本 0，然后二分搜索成本为 5 的点。根据方向，搜索自然会找到 5 或 15，两者都有效。 

对于所有相等的值：```
5 0
7 7 7 7 7
```中位数为 7，基本成本为 0。$d = 0$，算法立即返回 7 而不进行搜索。 

对于不可能的情况：```
3 1
0 0 0
```中位数为 0，基本成本为 0。但是，任何移动都会以 3 为步长增加成本，因此无法达到 1。 该算法检测到这一点是因为二分搜索永远找不到完全相等的值，并正确输出“否”。
