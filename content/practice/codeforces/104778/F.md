 ## 解决方案
 ## 问题理解

 我们从一排开始`n`最初的一堆盒子。 每叠`i`包含`a_i`盒子。 在每对相邻的初始堆栈之间，我们插入一个新的空堆栈，因此布局变成原始堆栈和新堆栈的交替序列：原始堆栈、新堆栈、原始堆栈、新堆栈，依此类推。 这会产生`2n − 1`总共堆栈。 

控制移动的一个关键限制是：盒子只能从原始堆栈移动到其相邻的新堆栈之一。 原堆垛之间不允许直接转移，新堆垛只接收箱子。 

任务是确定在经过一些允许的移动序列之后是否有可能使所有`2n − 1`堆栈中包含完全相同数量的盒子。 

盒子的总数是固定的，因此如果存在解决方案，则每个堆栈最终都必须具有相同的值`S = (sum of a_i) / (2n − 1)`。 这立即意味着总和必须能除以`2n − 1`，否则答案是不可能的。 

约束条件`n ≤ 200000`意味着任何解决方案都必须在大致线性的时间内运行。 二次或偶数`O(n log n)`在最坏的情况下，重复调整堆栈的贪婪模拟太慢。 我们应该期待一个基于前缀推理或本地可行性条件的解决方案。 

当平均值为整数但由于流量限制仍然无法重新分配时，会出现微妙的边缘情况。 例如，即使总和匹配，堆栈的某些前缀也可能需要将盒子“穿过”两个原始堆栈之间的禁止边界，这是不允许的。 这是主要的结构困难。 

## 方法

 一种简单的方法是直接模拟该过程。 我们建造`2n − 1`结构，反复挑选仍然有多余盒子的原始堆栈，并尝试将它们推入相邻的新堆栈，直到所有内容变得相等。 这类似于流动或平衡模拟。 然而，每个盒子的移动都是局部的，并且在最坏的情况下，单个盒子可能被调整多次。 高达`2n − 1`堆栈和潜在的`O(n)`每个堆栈的调整，这会退化为`O(n^2)`行为。 

关键的观察结果是新堆栈充当原始堆栈之间的缓冲区，并且它们隔离移动。 每个原始堆栈仅与其紧邻的左缓冲区和右缓冲区交互。 这将问题转化为局部可行性约束：每个原始堆栈必须能够将其盈余或赤字“拆分”到两个相邻的缓冲区位置，而不需要全局协调。 

我们重新制定该流程如下。 每个原始堆栈将其值贡献给两个相邻的间隙，并且每个间隙接收来自恰好两个相邻原始堆栈的贡献。 最终的配置是统一的，因此每个间隙也必须稳定一致地具有相同的目标值。 这将问题转换为检查原始节点推入边缘的路径图上是否存在一致的流分配。 

我们不进行模拟，而是从左到右导出约束：必须通过每个边界的数量由前缀不平衡唯一确定。 如果在任何时候所需的转移变得不可能，答案是否定的。

 | 模拟 | O(n²) | O(n) | 太慢了|
 | 前缀余额传播| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们计算目标值`S = sum(a) / (2n − 1)`。 如果不是整数，我们立即返回NO。 

然后我们将该系统解释为不平衡的线性传播。 让`balance`表示必须从当前原始堆栈传递到下一个区域的额外盒子数。 我们从左到右扫过原始堆栈，保持有多少盈余或赤字流过边界。 

1. 计算总和并检查整除性`2n − 1`。 如果失败，配置就无法均匀分配，所以我们立即停止。 
2. 设置每个堆栈的目标`S`。 
3. 初始化变量`carry = 0`，表示必须将多少个框从前一个段传递到当前段。 
4. 迭代每个原始堆栈`i`从左到右。 
5. 更新`carry`通过添加`a_i - S`。 这代表有多少堆栈`i`考虑流入流量后偏离目标。 
6. 如果在任何时候`carry`变为负数时，我们发现赤字必须向左推，这是不可能的，因为移动只能以一个一致的方向通过相邻的新堆栈传播。 
7. 继续传播直至结束。 
8. 如果处理完所有堆栈后系统一致，则返回 YES。 

关键的想法是`carry`对必须通过每个中间缓冲区的网络传输进行编码。 每个新堆栈只是充当一个管道； 除了强制流程的连续性之外，它不存储独立的约束。 

### 为什么它有效

 不变量是处理堆栈后`i`，值`carry`等于仍必须通过堆栈之间边界运输的箱子的净数量`i`和`i+1`以达到均匀性。 如果`carry`一旦变成负值，这意味着我们需要将盒子移向违反允许转移结构的方向，因为如果不经过禁止的原始到原始转换，早期的赤字就不能通过未来的盈余来纠正。 

因为每个边界只有一个自由度并且不存在环，所以这个前缀一致性条件对于可行性来说既是必要的也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    m = 2 * n - 1
    
    if total % m != 0:
        print("NO")
        return
    
    target = total // m
    
    carry = 0
    for x in a:
        carry += x - target
        if carry < 0:
            print("NO")
            return
    
    if carry == 0:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```该实现直接遵循前缀传播模型。 关键行是`carry += x - target`，它累积前缀与所需统一配置的偏差程度。 提前退出负数`carry`防止继续进入不可能的状态。 最终检查确保所有盈余到最后都被完全吸收，这意味着没有剩余的不平衡。 

一个常见的错误是忽略最终条件`carry == 0`。 即使没有前缀变为负数，剩余的正流也意味着盒子需要退出系统，这是不允许的。 

## 工作示例

 考虑存在有效重新分配的第一个样本。 

我们计算`S`并追踪`carry`:

 | 我| 一个[我] | a[i] - S | 携带|
 | ---| ---| ---| ---|
 | 1 | 7 | +2 | 2 |
 | 2 | 13 | +8 | 10 | 10
 | 3 | 5 | 0 | 10 | 10

 在此跟踪中，进位永远不会变为负值，并且系统保持一致的盈余，可以通过插入的堆栈进行分配。 最终的可行性对应于该剩余部分被结构完全吸收。 

现在考虑一种不可能解决不平衡问题的情况。 

| 我| 一个[我] | a[i] - S | 携带|
 | ---| ---| ---| ---|
 | 1 | 3 | -2 | -2 |

 这里进位立即变为负数，这意味着第一个堆栈已经需要无法从左侧获取的传入框。 由于不存在更早的结构，这种违反证明了不可能。 

这些例子说明可行性纯粹由前缀行为决定，而不是全局重新排列。

 ## 边缘情况

 当总和可被整除时，就会出现临界边缘情况`2n − 1`但前缀条件立即失败。 例如，如果第一个堆栈已经低于目标，则没有较早的缓冲区来弥补不足，因此算法在第一步正确地拒绝。 

另一个微妙的情况是当`carry`变得积极并保持积极直到最后。 这对应于无法吸收的剩余，因为没有机制将其输出到最后的边界之外。 最后检查`carry == 0`即使没有发生中间违规，也确保拒绝这种情况。 

这两个案例共同表明前缀可行性和全局守恒都是独立的必要条件。
