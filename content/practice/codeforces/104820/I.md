 ## 解决方案
 ## 问题理解

 我们被赋予了第一个$N$序列项$a_n = \frac{1}{n}$，产生值$1, \frac{1}{2}, \frac{1}{3}, \dots, \frac{1}{N}$。 除了这个序列之外，我们还给出了一个区间$[A, B]$，我们被要求数出其中​​有多少个$N$值落在该区间内，包括两个端点。 

因此，任务纯粹是过滤一组非常具体的数字，但微妙之处在于序列不是任意的，它是严格正数且单调递减的。 这种结构使得大部分区间在数轴的大部分区域中都变得无关紧要。 

约束条件允许$A$和$B$最多$10^9$的大小和$N$最多$10^9$。 这立即排除了任何迭代所有的方法$n \le N$，因为即使是线性扫描每次测试也需要多达十亿步，这远远超出了典型的限制。 任何有效的解决方案都必须将条件压缩为基于不等式的常量时间推理。 

一些边缘情况往往会打破天真的推理。 

一种有问题的情况是当区间完全位于负数一侧时，例如$A = -5, B = -1$。 每学期以来$1/n$严格为正，任何序列元素都不能落入这样的区间内，正确答案是$0$。 忘记符号并尝试反转不等式的幼稚实现可能会错误地包含索引。 

另一种情况是当间隔过零时，例如$A = -1, B = 2$。 这里序列的每个正项至少是$0$，以及所有值$1/n$位于$(0, 1]$，所以整个序列直到$N$包括在内。 如果人们错误地尝试对称地求解两个边界而不利用序列永远不会变为负的事实，则可能会错过这一点。 

第三种微妙的情况是当$A \ge 1$。 自从$1/n \le 1$为所有人$n$，只有第一项可以满足至少$1$，这迫使答案最多塌陷为一个元素。 

## 方法

 蛮力方法会迭代所有$n$从$1$到$N$, 计算$1/n$，并检查它是否位于$[A, B]$。 这是直接且正确的，因为它直接遵循序列的定义。 然而，它执行$N$划分和比较，当$N$达到$10^9$。 即使在$10^7$，这在 Python 中已经太慢了。 

关键的观察结果是序列$1/n$严格递减且始终为正。 我们可以翻译条件，而不是检查每个术语$$A \le \frac{1}{n} \le B$$进入约束条件$n$。 因为序列的行为是单调的，所以有效索引形成一个连续的范围，事实上整数的结构进一步简化了这一点。 

在上侧，$\frac{1}{n} \le B$仅当$B > 0$。 自从$B$是一个整数，任意正数$B$至少是$1$，因此每一项$1/n \le 1 \le B$。 所以上限永远不会限制任何东西，只要$B \ge 1$。 

在下侧，$\frac{1}{n} \ge A$很大程度上取决于是否$A$是积极的。 如果$A \le 0$，序列中的每一项都会自动满足它，因为所有项都是正数。 如果$A \ge 1$，那么只有值$1$（什么时候$n = 1$) 可能满足不等式。 

这将整个问题分解为几个恒定时间的情况，而不是数值搜索。

 ## 算法演练

 我们直接推理出哪里$1/n$可以相对于区间而言。 

1. 检查是否$B \le 0$。 如果是这样，则没有价值$1/n$可以拟合，因为所有序列元素都是严格正数。 答案立即为零。 
2.如果$A \le 0$和$B \ge 1$，序列的每一项都位于 0 和 1 之间（含 0 和 1），并且区间完全包含该区域。 每一个第一$N$条件符合条件。 
3.如果$A \ge 1$，那么条件$1/n \ge 1$力量$n = 1$。 然后，我们隐式检查该单个候选是否满足上限，只要间隔有效且有序，它就会执行此操作。 
4. 返回上述逻辑得到的计数。 

### 为什么它有效

 顺序$1/n$严格为正且严格递减。 这意味着任何区间查询都可以简化为了解有多少索引映射到单调变换。 因为函数在第一项之后永远不会过零且永远不会超过 1，所以所有有意义的约束都会崩溃为边界检查$n = 1$。 不可能存在多个不相交的有效段，因此对间隔是否低于零、跨越零或从一开始的案例分析完全可以确定答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    A, B, N = map(int, input().split())
    
    if B <= 0:
        print(0)
        return
    
    if A <= 0:
        print(N)
        return
    
    # now A >= 1 and B >= 1 (since A <= B)
    print(1 if N >= 1 else 0)

if __name__ == "__main__":
    solve()
```该实现遵循从结构导出的案例分割$1/n$。 第一个分支完全删除非正侧的所有区间，其中任何项都无法匹配。 第二个分支捕获其左边界上包含零或负值的任何区间，该区间自动包含最多可达的所有正序列值$N$。 最后一种情况完全处理从至少一个开始的正区域中的区间，其中只有第一项$1$可以符合资格。 

一个常见的陷阱是尝试计算阈值，例如$1/A$或者$1/B$使用浮点运算。 这在这里是不必要的，只会引入精度问题。 整数约束的结构允许解决方案完全避免除法。

 ## 边缘情况

 当$B \le 0$, 每一项$1/n$严格为正，因此没有一个可以落在该区间内。 对于像这样的输入$A = -10, B = 0, N = 5$，算法立即返回 0，无需进一步检查，这与即使是最大序列值$1$不满足$1 \le 0$。 

什么时候$A \le 0 < B$， 例如$A = -3, B = 2, N = 4$，每个序列值都位于$(0,1]$，它完全包含在区间内。 算法选择分支$A \le 0$并返回$N = 4$，与所有四个术语均有效一致。 

什么时候$A \ge 1$， 例如$A = 3, B = 10, N = 6$， 仅有的$1/1 = 1$有任何机会满足下界。 自从$1$也在区间内，无论多大，答案都是1$N$是。
