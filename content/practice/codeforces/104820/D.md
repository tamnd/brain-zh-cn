 ## 解决方案
 ## 问题理解

 该序列从单个数字字符串开始，并通过重复获取前一个字符串、附加当前索引的十进制表示形式、然后再次附加前一个字符串来增长。 所以每一步都会将之前的内容加倍，并在中间插入一个数字。 

我们没有被要求构建这些字符串。 任务只是确定位置 n 处的最终字符串将包含多少个字符。 

关键的观察是，只有数字的长度很重要，而不是它的值。 当我们插入 i 时，我们插入的正是 i 的位数。 因此，该结构是纯粹的组合：每个阶段仅取决于先前的长度和位数。 

输入 n 可以大到 10^9。 这立即排除了任何迭代从 1 到 n 的所有索引的方法。 即使 O(n) 也远远超出了可行的极限，甚至 O(n log n) 的思考也太慢了，除非对数因子非常小并且常数微不足道。 任何可行的解决方案都必须在不模拟每个步骤的情况下计算答案。 

简单的递归扩展会反复将字符串加倍，从而导致时间和内存呈指数增长，并且即使 n 约为 30，它也会几乎立即溢出内存。 

如果尝试仅迭代计算直到 n 的长度，则会出现一种更微妙的故障模式。 即使这是不可能的，因为 n 本身太大，因此 i 从 2 到 n 的任何按索引循环都不会及时终止。 

## 方法

 第一个简化是完全忘记字符串并仅跟踪它们的长度。 令L_i表示F_i的长度。 从构造上看，每个 F_i 由 F_{i-1}、i 的十进制表示形式、然后是 F_{i-1} 组成。 这直接给出了递归。 

暴力重现很简单。 从 L_1 = 1 开始，我们计算 L_i = 2 * L_{i-1} + d(i)，其中 d(i) 是 i 中的位数。 这是正确且容易推导的。 然而，计算到 n 需要迭代所有 i，当 n 达到 10^9 时这是不可能的。 

关键的结构问题是 L_i 通过重复加倍依赖于所有先前的值。 如果我们扩大递归范围，随着我们前进，每个较早的数字贡献都会重复加倍。 这建议展开递归而不是迭代它。 

展开递推式可以看出，每个 d(i) 都乘以 2 的幂，具体取决于它距 n 的距离。 这将问题转换为从 2 到 n 的所有 i 的加权和，其中权重为 2^{n-i}。 这将问题从指数上的动态规划转换为具有指数权重的算术范围上的求和。 

现在的困难转移到在不迭代所有值的情况下对 i 的贡献求和。 由于 d(i) 在 [1..9]、[10..99]、[100..999] 等区间内是恒定的，因此我们可以将范围 [1..n] 划分为数字长度的块。 在每个块中，我们必须对 2^{n-i} 乘以常数的形式求和。 

分解掉 2^n 后就变成了几何级数。 余下的和为2^{-i}，形成比例为1/2的递减等比数列。 因此，可以使用模幂在 O(1) 中评估每个块。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力重复最多 n | O(n) | O(1) | O(1) | 太慢了|
 | 具有几何和的范围分解 | O(log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们首先重写递归式，这样就可以在不从 1 迭代到 n 的情况下对其进行评估。

1. 定义L_n为最终字符串的长度。 从 L_1 = 1 开始。这是唯一的基值，因为序列完全由它确定。 
2. 将递归展开一次：每一步将前一个字符串加倍并添加 d(i)。 重复展开表明，每个早期的贡献都会乘以 2 的幂，具体取决于它被结转的次数。 
3. 根据该展开式，将结果表示为

 L_n = 2^{n-1} + sum_{i=2..n} d(i) * 2^{n-i}。 

第一项对应于开始时在所有级别中重复的原始单个字符。 
4. 从求和部分分解出 2^n，将总和重写为

 L_n = 2^{n-1} + 2^n * sum_{i=2..n} d(i) * 2^{-i}。 

这将对 i 的所有依赖隔离为 1/2 次方。 
5. 定义 inv2 = 2^{-1} mod M。则 2^{-i} 变为 inv2^i。 该问题简化为计算 inv2 幂的加权和：

 d(i) * inv2^i 之和。 
6. 将区间 [2..n] 分割为 d(i) 恒定的块。 每个块对应相同数字长度k的数字，例如[10^{k-1}, 10^k - 1]，在n处截断。 
7. 对于固定块 [l..r]，使用几何级数计算 sum_{i=l..r} inv2^i。 第一项是inv2^l，比率是inv2。 该总和可以使用有限几何级数的标准封闭形式来计算。 
8. 将块和乘以k（数字长度）并累加到总加权和中。 
9. 组合所有内容：将总加权和乘以 2^n，然后加上 2^{n-1}，并返回模 1e9+7 的结果。 

### 为什么它有效

 正确性来自于跟踪每个插入的数字如何通过递归加倍结构传播。 序列 F_i 的每个元素在创建后每一步都会在所有后续字符串中恰好出现两次，这会根据其到 n 的距离产生 2 次方的乘法因子。 递归展开式准确地捕获了这种传播。 将其转换为 i 上的加权和保留了该贡献结构，而无需显式模拟序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modpow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def digits(x):
    return len(str(x))

n = int(input())

inv2 = (MOD + 1) // 2

pow2_n = modpow(2, n)
inv2_pow = lambda e: modpow(inv2, e)

total = 0
start = 2

max_pow = 1
while max_pow <= n:
    max_pow *= 10

cur = 1
while cur <= n:
    l = cur
    r = min(n, cur * 10 - 1)
    k = len(str(cur))

    len_seg = r - l + 1

    first = modpow(inv2, l)
    ratio = modpow(inv2, len_seg)

    denom = (1 - inv2) % MOD
    inv_denom = modpow(denom, MOD - 2)

    seg_sum = first * (1 - ratio) % MOD
    seg_sum = seg_sum * inv_denom % MOD

    total = (total + k * seg_sum) % MOD

    cur *= 10

ans = (modpow(2, n - 1) + pow2_n * total) % MOD
print(ans)
```实现直接遵循闭式推导。 求幂助手用于所有模幂，因为指数可以大到 n。 数字块上的循环利用了具有相同数字长度的数字形成连续范围的事实，因此每个块贡献一个几何级数项。 

一个微妙的点是几何级数分母。 由于 inv2 = 1/2，因子 (1 - inv2) 是模可逆的，其逆用于对总和进行归一化。 

最终表达式将初始贡献 2^{n-1} 与按 2^n 缩放的累积加权数字贡献相结合。 

## 工作示例

 考虑 n = 3。 

我们有：

 L_1 = 1

 L_2 = 2 * 1 + 1 = 3

 L_3 = 2 * 3 + 1 = 7

 该算法通过以下方式计算相同的内容：

 L_3 = 2^{2} + 2^3 * (d(2)*2^{-2} + d(3)*2^{-3})

 | 我| d(i) | d(i) | 2^{-i}| 贡献 |
 | --- | --- | --- | --- |
 | 2 | 1 | 1/4 | 1/4 1/4 | 1/4
 | 3 | 1 | 1/8 | 1/8 |

 总和为 3/8，因此：

 L_3 = 4 + 8 * 3/8 = 7。 

该迹线证实，2 的倒数幂的加权正确地捕获了每个数字在未来加倍过程中的传播方式。 

现在考虑 n = 4。 

直接计算：

 L_1 = 1

 L_2 = 3

 L_3 = 7

 L_4 = 2 * 7 + 1 = 15

 加权形式：

 L_4 = 8 + 16 * (d(2)/4 + d(3)/8 + d(4)/16)

 | 我| d(i) | d(i) | 2^{-i} | 2^{-i} | 贡献 |
 | --- | --- | --- | --- |
 | 2 | 1 | 1/4 | 1/4 1/4 | 1/4
 | 3 | 1 | 1/8 | 1/8 |
 | 4 | 1 | 1/16 | 1/16 1/16 | 1/16

 总和为 7/16，得出：

 L_4 = 8 + 16 * 7/16 = 15。 

这证实了多个步骤中推导公式的一致性。

 ## 边缘情况

 对于 n = 1，递归永远不会扩展，因此答案必须保持为 1。该算法处理此问题是因为 i 上的求和从 2 开始，产生空贡献。 仅保留基本项 2^{n-1}，当 n = 1 时等于 1。 

对于 n = 10，数字长度边界恰好在 10 处交叉，这意味着块结构从一位数变为两位数。 几何级数处理确保了该边界处的分割不需要特殊的大小写，因为每个块都是独立的并且在 n 处被正确截断。 

对于较大的 n（例如 10^9），不会发生对各个 i 值的迭代。 该算法仅评估恒定数量的几何级数项，并且所有求幂均在对数时间内处理，因此即使在最大输入大小下，性能也保持稳定。
