 ## 解决方案
 ## 问题理解

 我们被要求构造一个精确的数字`n`数字，其中每个数字必须来自`1`到`9`。 没有数字`0`任何地方都允许，所以我们完全在正数字字符串的范围内工作。 

定义“美”的约束是通过滑动固定长度的窗口来施加的`k`跨越数。 对于每个连续的块`k`数字，我们计算该块内的数字之和。 这些和形成一个序列，并且该序列必须严格从左到右递增。 

任务不是计算这些数字或决定可行性。 我们必须在这些约束下构造字典顺序最大的有效数字。 

关键的张力在于重叠窗口的局部限制与最大化数字的全局目标之间。 

限制条件`n, k ≤ 100000`意味着任何解决方案都必须在线性时间内运行。 任何二次计算，尤其是独立重新计算每个位置的窗口总和的任何计算，都将立即失败。 由于每个数字影响最多`k`windows，简单的重新计算直接导致`O(nk)`的行为，远远超出了界限。 

出现微妙的边缘情况时`k = 1`。 那么每个窗口都是个位数，条件就变成了数字严格从左到右递增。 最大可能的数量就是`123...9`截断长度`n`，它独立于任何重叠结构。 

另一个极端情况是`k = n`。 只有一扇窗户，所以根本没有可比性。 每个数字从`1`到`9`是有效的，所以最大值就是全部`9`s。 

## 方法

 直接的暴力方法将尝试构建所有可能的长度数字字符串`n`使用数字`1`到`9`，检查滑动窗口总和，并跟踪最佳有效候选者。 这在概念上很简单：按字典顺序生成、验证和比较。 然而，这样的字符串的数量是`9^n`，甚至早期修剪也无济于事，因为约束取决于重叠窗口，因此部分分配不能可靠地消除大部分搜索空间。 即使检查单个候选人也需要`O(nk)`或者`O(n)`工作依赖于预计算，使得整体方法完全不可行。 

关键的结构观察是连续位置之间的窗口总和仅相差两位数：从窗口移动时`[i, i+k-1]`到`[i+1, i+k]`，总和通过删除而改变`a[i]`并添加`a[i+k]`。 这意味着约束```
sum[i] < sum[i+1]
```翻译成```
sum[i] - a[i] + a[i+k] > sum[i]
```这简化为```
a[i+k] > a[i]
```这是关键的减少：而不是比较长度之和`k`，我们只比较数字`k`分开。 该条件成为跨固定步长的简单单调性约束。 

所以问题变成了构造字典序上最大的序列，使得对于每个`i`，我们有`a[i+k] > a[i]`。 现在，这是由 分隔的位置之间的直接依赖关系`k`，根据残基类别模形成独立链`k`。 

我们可以单独处理每个链，确保沿着它严格增加值，同时按字典顺序最大化。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(9^n·n) | O(9^n·n) | O(n) | 太慢了 |
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们利用仓位分为以下这一事实：`k`独立序列：索引`i, i+k, i+2k, ...`。 

1. 将索引拆分为`k`基于索引模的链`k`。 每条链必须满足从左到右严格递增的值。 这直接来自转换后的约束`a[i] < a[i+k]`。 
2. 对于每个链，确定它包含多少个元素。 这确定了我们必须分配多少个严格递增的数字。 
3.对于长度的链条`len`，我们需要分配`len`数字选自`1`到`9`，严格增加。 为了最大化字典顺序，我们希望原始字符串中后面的位置尽可能大，因此我们更喜欢将大数字分配给每个链中后面的索引。 
4. 按链顺序从左到右贪婪地构建每个链，始终选择仍允许完成的最小可能数字。 这相当于为严格增加的赋值保留足够的空间。 在位置`t`在一条长度的链中`len`，该数字必须至少为`len - t`步数低于 9，给出有界的可行区间。 
5. 计算完所有链值后，通过将每个链值放回其原始索引来重建完整数字。 

微妙之处在于每条链都是独立的。 没有约束连接不同的残基类别，因此单独优化每个链会产生全局最优值。 

### 为什么它有效

 该变换将重叠窗口总和的原始条件减少为固定距离位置之间的局部约束。 这消除了不同残基类模之间的所有耦合`k`。 在每条链中，严格的不平等迫使单调递增的序列，并且通过在尊重可行性的同时将较大的数字尽可能向右推来实现字典序最大化。 由于一条链中的选择永远不会影响另一条链，因此结合最优链解决方案可以保持全局最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    
    # split indices into k chains
    chains = [[] for _ in range(k)]
    for i in range(n):
        chains[i % k].append(i)
    
    ans = [0] * n
    
    # process each chain independently
    for chain in chains:
        m = len(chain)
        if m == 0:
            continue
        
        # we assign increasing digits; best is to push small digits early
        # and ensure we can still reach up to 9
        start = 1
        for t, idx in enumerate(chain):
            # we need enough room to place strictly increasing digits up to 9
            # remaining positions = m - t
            # so max feasible start is 10 - (m - t)
            val = max(start, 10 - (m - t))
            ans[idx] = val
            start = val + 1
    
    print("".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```实施构建`k`通过将具有相同余数模的索引分组来独立链`k`。 然后贪婪地填充每个链。 变量`start`跟踪严格增加允许的最小可能数字。 表达式`10 - (m - t)`强制保留足够的数字来完成严格递增的序列，最多可达`9`。 如果没有这个约束，构造可能会超出范围并且不会留下有效的延续。 

最后，数字被写回其原始位置并连接到输出字符串中。

 ## 边缘情况

 当`k = 1`，每个位置都形成自己的链，并且必须在整个数组中严格递增。 该算法通过以下方式强制可行性`10 - (m - t)`约束，它产生仍然适合数字的最小可能的递增序列，产生`123...`。 

什么时候`k = n`，每条链的长度为一。 该公式允许分配`9`立即，因为不存在未来的约束，所以每个数字都变成`9`。 

什么时候`n < k`，大多数链都是空的或单元素的，并且相同的逻辑无需特殊处理即可正确退化，因为没有链需要多个递增步骤。
