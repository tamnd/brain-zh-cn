 ## 解决方案
 ## 问题理解

 我们得到一个小写拉丁字母的字符串。 我们可以重复选择任何位置并将其字符替换为任何其他字母。 每次更换的成本为 1，我们希望使总成本最小化。 

所有变化之后我们必须满足的约束是全局的：每个长度为奇数的子串必须是回文。 这意味着，如果我们取最终字符串中长度为 1、3、5 等的任何一段，从左到右读取它必须与从右到左读取它相匹配。 

任务是计算使字符串满足此属性所需的最小字符更改数。 

字符串长度最多为 50000，因此任何尝试检查所有子字符串的解决方案都立即不可能。 子串的数量是二次方的，即使检查每个子串的回文性，在最坏的情况下也会将其推至三次方。 即使每个子串的线性扫描仍然远远超出限制。 

一个微妙的点是，该条件适用于所有奇数长度的子字符串，而不仅仅是前缀或整个字符串。 一个天真的错误是认为这相当于整个字符串是回文，但它要强大得多。 另一个常见的误读是假设它仅在局部约束中心对称性，而实际上它在全局范围内跨位置传播。 

例如，在像这样的字符串中`abca`，查看子串`abc`力量`a == c`，和子串`bca`力量`b == a`，它已经展示了约束如何快速连接遥远的位置。 

主要隐藏的困难是约束严重重叠，正确的解决方案必须识别由“所有奇数子串都是回文”引起的结构，而不是明确地检查它们。 

## 方法

 暴力方法将枚举每个奇数长度的子串，并在每组尝试性更改后验证它是否是回文。 即使我们只验证一个固定的字符串，检查所有子字符串也会花费 O(n²) 时间，并且在循环内执行任何操作都会使其不可行。 

一个稍微好一点但仍然不正确的方向是假设我们只需要整个字符串是回文。 这将导致经典的两指针不匹配计数问题。 然而，这忽略了较短的奇数子串的约束，这在非对称位置之间施加了额外的相等性。 

关键的观察是将条件重新解释为字符之间的平等约束系统。 每个奇数长度的子串都强制其中心周围的镜像位置之间相等。 这些约束在整个字符串中传递传递。 

如果我们从任何位置开始，我们可以以两步移动（因为奇数长度子串中的对称性总是将具有相同奇偶校验距离结构的索引相关联）。 这将创建两组独立的索引：所有奇数位置形成一个连通分量，所有偶数位置形成另一个连通分量。 在每个组中，最终字符串中的所有字符都必须相同。 

一旦认识到这一结构，问题就简化为为所有奇数索引选择一个最终字符，为所有偶数索引选择一个最终字符，从而最大限度地减少替换。 

对于每个奇偶组，我们计算字母频率并保持最常见的字符不变，同时更改所有其他字符。

 | --- | --- | --- | --- |
 | 子串暴力破解 | O(n3) | O(1) | O(1) | 太慢了|
 | 最佳奇偶分组 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们处理字符串一次并通过索引奇偶校验分隔信息。 

1. 将索引分为两组：位置 0,2,4,... 和位置 1,3,5,...（或基于 1 的奇数和偶数）。 这种分离是自然的，因为对称约束仅连接具有相同奇偶校验结构的位置。 
2. 统计奇数索引组中每个字母的出现频率。 这告诉我们有多少位置已经与选择给定的最终字母兼容。 
3. 以同样的方式统计偶数索引组中每个字母的出现频率。 
4. 对于奇数组，确定所有字母中出现的最大频率。 这代表了该组最终字符的最佳选择，因为保留最常见的字母可以最大限度地减少替换。 
5. 将奇数位置的替换数计算为总奇数位置减去该最大频率。 
6. 对偶数位置重复相同的计算。 
7. 将两个值相加并返回结果。 

选择最频繁的字符背后的原因是，组中的每个位置最终都必须相同，因此与所选字符的每次不匹配都会花费​​一次替换，这使得这是一个直接的频率最大化问题。 

### 为什么它有效

 每个奇数长度子串都是回文的约束强制所有可能中心的对称对之间相等。 这些约束在字符串中传递传递，将相同奇偶校验的所有索引链接到单个等价类中。 在每个类中，任何有效的最终字符串中的所有字符都必须相同。 由于每个位置都可以独立更改，因此通过选择每个类别中最常见的现有字符来实现最佳解决方案，从而最大限度地减少统一类别所需的更改数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    odd = [0] * 26
    even = [0] * 26

    for i, ch in enumerate(s):
        if i % 2 == 0:
            odd[ord(ch) - 97] += 1
        else:
            even[ord(ch) - 97] += 1

    odd_len = (n + 1) // 2
    even_len = n // 2

    best_odd = max(odd)
    best_even = max(even)

    print((odd_len - best_odd) + (even_len - best_even))

if __name__ == "__main__":
    solve()
```其实现直接遵循奇偶校验分解。 唯一的微妙之处是正确计算组大小：从零开始的索引将位置 0,2,4 放入第一组，因此其大小为`(n + 1) // 2`。 

一个常见的错误是通过频率求和来重新计算组大小，这是不必要但安全的，或者混合基于 0 和基于 1 的索引并意外交换奇偶校验组。 该代码通过始终使用基于 0 的索引来避免这种情况。

 ## 边缘情况

 一种边缘情况是单字符字符串，例如`x`。 每个奇数长度的子串只是字符本身，因此它已经是一个回文。 该算法将该字符放入奇数位置组中，看到最大频率为 1，并正确返回 0。 

另一种情况是长度为 2 的字符串，例如`ab`。 不存在长度大于 1 的奇数长度子串，因此不存在超出简单长度为 1 的子串的约束。 该算法分为一个奇数位置和一个偶数位置，每个位置有一个字符，并且不需要替换。 

一个更微妙的情况是高度混合的字符串，例如`abcabcabc`。 尽管它看起来是结构化的，但奇偶分组迫使奇数和偶数索引独立同质化。 该算法正确地忽略了较长的模式，仅关注每个组内的频率优化，从而产生最小的转换成本。
