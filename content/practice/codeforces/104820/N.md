 ## 解决方案
 ## 问题理解

 我们有几种音乐流派，每种流派都有固定数量的歌曲。 任务是决定是否可以将所有歌曲排列在一个播放列表中，以便没有两首相邻歌曲属于同一流派。 

另一种思考方式是，我们尝试将多组相同的项目交错排列。 每种流派的行为就像一块相同的标记，我们必须排列一行中的所有标记，同时避免相同的邻居。 

输入大小最多允许 100,000 个流派，每个流派最多可以贡献 10,000 首歌曲。 这意味着歌曲总数可能非常大，可能高达 10^9。 任何尝试显式构造或模拟排列的解决方案都是不可能的。 如果迭代完整的扩展序列，即使对单首歌曲进行排序和贪婪模拟也会太慢。 

时间限制意味着我们应该在 O(n) 或 O(n log n) 范围内处理流派数量，而不是歌曲总数。 

当一种类型主导其他类型时，就会出现一个关键的边缘情况。 例如，如果我们有 1000, 1, 1, 1 这样的计数，那么显然不可能插入足够多的其他歌曲来分隔所有出现的主导流派。 仅检查总和或奇偶校验的天真的方法在这里会失败，因为最大堆的结构很重要，而不仅仅是聚合。 

另一个微妙的情况是，两大流派共同主导其余流派。 例如，像 50, 49, 1, 1, 1 这样的计数仍然有效，但是如果实施不正确，仅将最大值与其他总和进行比较而没有精确的不平等推理的小误判可能会产生误导。 

## 方法

 蛮力策略会尝试显式构建播放列表。 人们可以反复选择与最后放置的歌曲不同的流派，在可用流派中贪婪地选择。 这类似于具有优先级结构的模拟。 每个位置都需要选择一个有效的下一个流派，在最坏的情况下，我们对每首可能数十亿首歌曲进行线性或对数选择。 由于总歌曲数是所有 a_i 的总和，这会导致 O(总歌曲 log n) 或更糟，这是不可行的。 

关键的观察是我们不需要确切的安排，只需要它的存在。 这个问题归结为一个经典的可行性条件：我们能否使用所有其他歌曲作为分隔符来分隔最常见的流派的出现。 

如果一种流派的歌曲太多，它不可避免地会迫使其与其自身相邻。 想象一下将所有其他歌曲放在第一位作为分隔符。 每个分隔符最多可以打破两次出现的主导流派之间的一个邻接关系。 如果最大的计数大于其他歌曲的总数加一，那么就没有办法避免邻接。 

令 max 为最大的 a_i，sum 为歌曲总数。 非最大歌曲数量为总和 - 最大。 我们至少需要 max-1 的间隙来在最大流派的出现之间放置其他歌曲。 因此，条件变为：

 最大值 - 1 ≤ 总和 - 最大值

 简化为：

 最大值 ≤ 总和 - 最大值 + 1

 如果这种不等式失效，则不存在任何安排。 否则，我们总是可以使用贪婪交错参数构造有效的排序，因此该条件是充分且必要的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(总歌曲数 log n) | O(n) | 太慢了 |
 | 最大频率条件| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 读取所有流派计数并计算它们的总和和最大值。 这反映了分布集中程度的全球结构。 
2. 确定最大的计数，因为只有最常见的类型才会导致不可避免的邻接问题。 所有其他类型如果数量充足，则始终可以用作分隔符。 
3. 通过从总和中减去最大值来计算有多少歌曲不属于主导流派。 这些是唯一可用的分隔符。 
4. 检查可用分隔符的数量是否至少为 max - 1。这是任何有效序列中主导流派出现之间的间隙数量。 
5. 如果条件成立，输出“Yes”，否则输出“No”。 

### 为什么它有效

 正确性取决于填补空白的论证。 最常见流派的任何排列都会在其出现次数之间精确创建 max - 1 强制间隙。 如果我们想避免相邻，那么其他每一首歌最多只能占据一个这样的间隙。 如果非主导歌曲的数量少于间隙，则至少有一个间隙必须保持空白，迫使两种相同的流派接触。 相反，如果存在足够的分隔符，我们总是可以将它们分布在间隙中，然后插入剩余的主导元素而不破坏可行性，确保存在有效的排列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    mx = max(a)
    
    if mx <= total - mx + 1:
        print("Yes")
    else:
        print("No")

if __name__ == "__main__":
    solve()
```实现直接遵循导出条件。 所有计数的总和计算一次，并在一次遍历数组时提取最大值。 最终的不等式编码了整个可行性条件，因此不需要进一步的模拟。 

一个微妙的点是`+1`在条件下。 它对应于最大的类型可以占据序列的两端的事实，因此它需要比其计数少一个分隔符。 

## 工作示例

 ### 示例 1

 输入：```
3

```我们计算出 Total = 6 且 mx = 3。 

| 步骤| 总计 | MX | 总计 - mx | 状况 |
 | ---| ---| ---| ---| ---|
 | 开始 | 0 | 0 | 0 | - |
 | 看完后| 6 | 3 | 3 | 检查 3 ≤ 4 |

 我们检查是否 3 ≤ 6 - 3 + 1 = 4，这是真的，所以答案是 Yes。 

这展示了一种平衡的分布，其中最大的流派可以使用剩余的歌曲进行交织。

 条件成立，所以答案是肯定的。 这证实了即使是最小的对称情况也是有效的。

 ## 边缘情况

 一个关键的边缘情况是只有一种类型。 对于输入：```
1
5
```我们计算total = 5，mx = 5。条件变为5 ≤ 1，这是假的，因此输出为No。这正确地反映了任何相同歌曲的序列将始终违反邻接规则。 

另一个边缘情况是最大的流派刚刚太大。 为了：```
4
1 1 1 4
```我们有 Total = 7 和 mx = 4。条件是 4 ≤ 4，这是正确的，所以答案是 Yes。 通过将单例放置在最大流派的出现之间，存在有效的安排。 

最后，考虑一个紧密包装的故障案例：```
3
1 1 3
```这里total = 5，mx = 3。条件是3 ≤ 3，所以它是有效的。 我们可以构造一个像 3 1 3 1 3 这样的序列，这表明相等正是可能配置和不可能配置之间的边界。
