 ## 解决方案
 ## 问题理解

 我们正在处理从 1 到 n 的数轴上的一个点。 青蛙从位置 1 开始，想要到达位置 n。 每次移动，它都可以向前跳跃 1 步或 2 步。 这已经是标准的“计算一条线上的路径”问题，但还有一个额外的约束：在整个旅程中，青蛙最多只能向后跳跃一次，并且向后跳跃的长度可以是任意正长度。 

不允许青蛙离开段[1,n]。 一旦到达位置n，它立即停止并且不能执行任何进一步的移动，包括向后跳跃。 

任务是计算在这些规则下从 1 到 n 有多少个不同的移动序列，模 10^9 + 7。 

输入大小 n 达到 10^6，这会立即排除任何指数路径探索。 即使是跟踪是否使用向后移动的简单动态规划也已经很严格，但如果仔细优化，仍然是可行的。 然而，困难不仅仅在于计算前进的步数，还在于处理可能在任何时刻、任何距离发生的单一全局向后跳跃。 

一个关键的微妙之处在于，向后跳跃可以落在左侧的任何位置，这意味着它有效地允许路径以非本地方式“重新访问”早期状态。 仅跟踪位置的粗心 DP 会少计数或多计数，除非它根据是否已使用向后跳转来仔细分隔状态。 

当 n 非常小时，就会出现典型的边缘情况。 当 n = 1 时，青蛙已经到达目的地，因此只有一条空路径。 对于 n = 2，仅存在单个直接移动。 对于 n = 3，示例显示了 4 种方式，这已经表明即使对于较小的 n，向后跳转也会显着增加组合复杂性。 

主要的挑战是考虑到向后跳跃可以从任何位置发生并在任何地方更早着陆，从而有效地创建依赖于所有未来状态（而不仅仅是本地邻接状态）的聚合贡献的转换。 

## 方法

 如果我们完全忽略向后跳跃，问题就变成了经典的斐波那契式计数：令 dp[i] 为使用 +1 和 +2 步到达 i 的方法数。 然后 dp[i] = dp[i-1] + dp[i-2]，其中 dp[1] = 1 且 dp[2] = 1。这以线性时间运行并且很简单。 

向后跳跃引入了第二阶段。 强力解释将尝试模拟所有路径，并且在每一步中，可选择执行向后跳转到某个较早的位置，标记允许的向后移动已被消耗。 这很快就会爆炸：即使我们只在使用向后跳转时以及它落地时分支，每个长度为 O(n) 的前向路径都有 O(n^2) 可能的向后跳转选择。 这会导致朴素枚举中至少 O(n^3) 规模的行为，这远远超出了限制。 

需要一个更加结构化的视图。 关键的观察是路径可以分解为两个阶段。 首先，青蛙仅使用 +1 和 +2 步向前移动，直到某个点。 然后，最多一次，它可能会向后跳，提前降落在某个地方。 在向后跳跃之后，它再次仅使用 +1 和 +2 步向前移动，直到到达 n。 向后跳跃有效地将轨迹分成两个独立的前向 DP 段，通过单个转换粘合在一起。 

这表明了 DP 状态分离：我们跟踪在不使用向后跳转的情况下可以到达每个位置的方式有多少种，以及已经使用向后跳转的情况下我们可以到达每个位置的方式有多少种。 第二个状态接收来自两个来源的贡献：从先前的“已使用”状态继续前进，并从任何“未使用”状态开始向后跳跃并更早着陆。

关键的简化是将向后跳跃重新解释为不是任意位置之间的直接过渡，而是将质量从某个位置 i 的“未使用”DP 转移到所有位置 j < i 的一种方式。 这可以通过前缀和来处理，以便 O(n^2) 传输压缩为 O(n)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力路径枚举| 指数| O(n) | 太慢了 |
 | 具有状态 + 前缀和的 DP | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们维护两个数组：dp0[i]表示不使用向后跳转到达i的方式数量，dp1[i]表示使用向后跳转后到达i的方式数量。 

我们还使用 dp0 上的前缀和来有效地分配向后跳跃的贡献。 

## 步骤

 1. 初始化 dp0[1] = 1 和 dp1[1] = 0，因为我们从位置 1 开始，没有使用向后跳转。 这建立了进程的基本配置。 
2. 对于从 2 到 n 的每个位置 i，将 dp0[i] 计算为 dp0[i-1] + dp0[i-2]。 这计算了仅使用向前移动到达 i 的所有方法，因为在使用向后跳跃之前，问题的行为与斐波那契路径完全相同。 
3. 维护前缀和 pref0[i] = pref0[i-1] + dp0[i]。 这种结构允许我们快速查询到任意点的“未使用的向后”路径的总数，这将在分配向后转换时使用。 
4. 分两部分计算 dp1[i]。 第一部分来自向后跳跃后的向前移动：dp1[i-1] + dp1[i-2]，因为一旦使用了向后跳跃，该移动再次成为标准向前DP。 
5. dp1[i] 的第二部分来自于在某个位置 j > i 处启动向后跳跃并在 i 处着陆。 每个 dp0[j] 都会对 dp1[i] 做出贡献，因为从任何这样的状态我们都可以选择跳回 i。 这个贡献正好是 pref0[n] - pref0[i]，代表 i 之外的所有未使用状态。 
6. 将两个贡献相加形成 dp1[i]，在每一步取模以防止溢出。 
7. 最终答案是 dp0[n] + dp1[n]，因为青蛙可能在不使用向后跳跃的情况下或在之前使用向后跳跃后到达 n。 

### 为什么它有效

 正确性来自于将所有有效路径划分为两个不相交的类别：那些从不使用向后跳转的路径和只使用一次向后跳转的路径。 在每个类别中，向前运动遵循相同的递归结构，因此 dp0 和 dp1 各自独立地遵循斐波那契转换。 通过将所有较早索引处的权重从 dp0 状态转移到 dp1 状态，可以完全捕获向后跳跃。 前缀总和确保每次有效选择跳转起点和目的地时，每次此类传输都被精确计数一次，从而避免重复或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n = int(input().strip())

if n == 1:
    print(1)
    sys.exit()

dp0 = [0] * (n + 1)
dp1 = [0] * (n + 1)
pref0 = [0] * (n + 1)

dp0[1] = 1
dp0[2] = 1 if n >= 2 else 0
dp1[1] = 0

pref0[1] = 1
if n >= 2:
    pref0[2] = pref0[1] + dp0[2]

for i in range(3, n + 1):
    dp0[i] = (dp0[i - 1] + dp0[i - 2]) % MOD
    pref0[i] = (pref0[i - 1] + dp0[i]) % MOD

for i in range(2, n + 1):
    dp1[i] = (dp1[i - 1] + dp1[i - 2]) % MOD

    # all dp0 states beyond i can jump back to i
    dp1[i] = (dp1[i] + (pref0[n] - pref0[i] + MOD) % MOD) % MOD

print((dp0[n] + dp1[n]) % MOD)
```该代码将计算分为基本前向 DP 和向后跳转后的增强 DP。 dp0 数组纯粹是类似斐波那契的，而 dp1 结合了斐波那契转换和通过前缀和从 dp0 进行的聚合传输。 

一个微妙的实现细节是计算 pref0[n] - pref0[i] 时模减法的处理。 如果在取模之前不添加 MOD，中间值可能会在 Python 中变为负值并破坏正确性。 

另一个重要的细节是正确初始化 dp0[2]，因为递归假设 i-2 存在。 对于 n = 1 或 2，直接处理可以避免索引问题。 

## 工作示例

 ### 示例 1：n = 3

 我们首先计算 dp0。 dp0[1] = 1，dp0[2] = 1，dp0[3] = 2。 

| 我| dp0[i] | dp0[i] | 首选项0[i] |
 | ---| ---| ---|
 | 1 | 1 | 1 |
 | 2 | 1 | 2 |
 | 3 | 2 | 4 |

 现在 dp1 已构建。 当 i = 2 时，dp1[2] = 0 + (pref0[3] - pref0[2]) = 4 - 2 = 2。当 i = 3 时，dp1[3] = dp1[1] + dp1[2] + (pref0[3] - pref0[3]) = 0 + 2 + 0 = 2。 

最终答案是 dp0[3] + dp1[3] = 2 + 2 = 4。 

该轨迹显示了向后跳跃如何通过有效地从较高的 dp0 状态“传送”到较早的位置来引入额外的方式，从而增加 dp1。 

### 示例 2：n = 2

 dp0[1] = 1，dp0[2] = 1，pref0[2] = 2。 

dp1[2] = (pref0[2] - pref0[2]) = 0。 

最终答案是 dp0[2] + dp1[2] = 1。 

这证实了只有两个位置，没有空间进行有益的向后跳跃来创建新的不同的有效路径结构。

 | 空间| O(n) | 数组 dp0、dp1 和 n | 上的前缀和存储

 对于 n 高达 10^6 的线性复杂度来说已经足够了，因为计算是纯算术的并且完全避免了嵌套循环。 内存使用量也是可以接受的，因为三个大小为 10^6 的整数数组完全符合典型限制。

import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(sys.stdin.readline().strip())

    if n == 1:
        return "1"

    dp0 = [0] * (n + 1)
    dp1 = [0] * (n + 1)
    pref0 = [0] * (n + 1)

    dp0[1] = 1
    dp0[2] = 1
    pref0[1] = 1
    pref0[2] = 2

    for i in range(3, n + 1):
        dp0[i] = (dp0[i - 1] + dp0[i - 2]) % MOD
        pref0[i] = (pref0[i - 1] + dp0[i]) % MOD

    for i in range(2, n + 1):
        dp1[i] = (dp1[i - 1] + dp1[i - 2]) % MOD
        dp1[i] = (dp1[i] + (pref0[n] - pref0[i] + MOD) % MOD) % MOD

    return str((dp0[n] + dp1[n]) % MOD)

# provided samples
assert run("1\n") == "1"
assert run("2\n") == "1"
assert run("3\n") == "4"

# custom cases
assert run("4\n") > "0"
assert run("5\n") > "0"
assert run("10\n") > "0"
assert run("20\n") > "0"

 ## 边缘情况

 对于 n = 1，算法直接返回 1，因为 dp0 和 dp1 都仅使用起始状态进行初始化。 没有任何移动的可能性，因此 DP 不会进入转换循环。 

对于 n = 2，dp0 只计算一条前向路径。 向后跳转没有任何有意义的效果，因为没有严格的后跳转位置来产生以 2 结尾的新配置。 dp1[2] 的前缀和贡献变为零，因此最终答案仍然为 1。 

对于像 3 这样的小 n，dp1 层变得活跃。 在 i = 3 时，dp0 已经提供了 2 条前向路径，并且 dp1 贡献了从位置 2 或 3 向后跳转而得出的附加配置。该算法通过前缀差异正确地累积这些配置，产生 4，而无需重复计算。
