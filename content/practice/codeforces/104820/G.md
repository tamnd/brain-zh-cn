 ## 解决方案
 ## 问题理解

 我们将三种不同类型的糖果分发给三个朋友，每个朋友只接受一种特定类型。 第一个朋友只拿士力架，第二个只拿火星，第三个只拿赏金。 我们得到了每种类型的可用数量：A 士力架、B 火星和 C 赏金。 

每个朋友必须至少收到一颗他们喜欢的糖果。 另外，收到的糖果数量必须严格从第一个朋友到第二个、从第二个到第三个增加。 这意味着，如果我们将分配量表示为 x、y、z，则 x、y、z 必须满足 x < y < z，其中 x ≥ 1、y ≥ 1、z ≥ 1，并且 x ≤ A、y ≤ B、z ≤ C。 

任务是计算有多少个三元组 (x, y, z) 满足所有这些约束。 

约束达到 10^6，这会立即排除迭代所有可能的三元组。 在最坏的情况下，朴素的三次甚至二次枚举将产生多达 10^18 次迭代，这远远超出了可接受的限制。 解决方案必须将问题简化为线性扫描或直接组合计数公式。 

当 A、B 或 C 中的任何一个为 1 时，就会出现微妙的边缘情况。例如，如果 A = B = C = 1，则唯一可能的三元组将是 (1, 1, 1)，这违反了严格的不等式，因此答案为 0。忘记严格排序的幼稚方法可能会错误地将其视为有效。 

当容量较小但不相等时，会出现另一种边缘情况，例如 A = 1、B = 2、C = 3。只有一个三元组 (1, 2, 3) 有效，任何对“至少一个”与“精确分配选择”的误解都可能导致计数过多。 

## 方法

 暴力方法会尝试 x 从 1 到 A、y 从 1 到 B、z 从 1 到 C 的所有可能值，检查是否 x < y < z。 这是正确的，因为它直接强制执行所有约束，但其复杂度为 O(ABC)。 每个变量最多为 10^6，这会在最坏的情况下导致 10^18 次操作，这是不可行的。 

关键的观察结果是，约束仅取决于排序，而不取决于超出其类型限制的糖果的身份。 我们正在有效地计算严格递增的三元组，其中每个元素都受到独立上限的限制。 这可以重新定义为选择 x、y、z，使得 1 ≤ x < y < z，具有独立的上限。 

我们可以修复中间值 y，而不是迭代所有三元组。 一旦 y 固定，x 可以是 [1, y−1] 中的任意整数，但也不能超过 A，因此 x 受 min(A, y−1) 限制。 类似地，z 必须在 [y+1, C] 中，但也不能超过 C，并且必须严格大于 y 且至少为 1，另外必须遵守 B，因为 y 是从 Mars 极限分配的，而不是 z。 实际上z只取决于C。 

因此，对于每个 y，有效 x 选项的数量为 min(A, y−1)，有效 z 选项的数量为 max(0, C − y)。 每个 y 的贡献变为 min(A, y−1) × max(0, C − y)，但前提是 y ≤ B。 

这将问题简化为 y 从 1 到 B 的单个循环，从而提供 O(B) 时间。 由于 B 最大可达 10^6，所以这是可以接受的。

 | ---| ---| ---| ---|
 | 蛮力 | O(ABC) | O(1) | O(1) | 太慢了 |
 | 固定中间枚举| O(B) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 迭代 y 从 1 到 B 的所有可能值。这代表给第二个朋友的糖果数量，并确保我们尊重火星糖果的限制。 
2. 对于每个 y，计算 x 存在多少个有效选择。 由于 x 必须满足 1 ≤ x < y 且 x ≤ A，因此有效范围为 1 到 min(A, y−1)。 如果 y = 1，则该范围为空，这会正确产生零个选择。 
3. 对于相同的 y，计算 z 存在多少个有效选择。 由于 z 必须满足 z > y 且 z ≤ C，因此有效范围为 y+1 到 C，其大小为 max(0, C − y)。 
4. 将有效 x 选项的数量乘以有效 z 选项的数量。 这是可行的，因为一旦 y 固定，x 和 z 就是独立的，因此每个有效对形成一个唯一的三元组。 
5. 对从 1 到 B 的所有 y 的贡献求和。 

为什么有效：每个有效的三元组 (x, y, z) 都由其中间元素 y 唯一标识。 对于每个这样的 y，算法精确计算约束下左侧的所有有效 x 选择和右侧的所有有效 z 选择。 没有三元组会被计算两次，因为每个三元组只有一个中间元素，并且不会计算无效三元组，因为双方都严格执行边界和排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    A, B, C = map(int, input().split())
    
    ans = 0
    for y in range(1, B + 1):
        x_cnt = min(A, y - 1)
        if x_cnt <= 0:
            continue
        z_cnt = C - y
        if z_cnt <= 0:
            continue
        ans += x_cnt * z_cnt
    
    print(ans)

if __name__ == "__main__":
    solve()
```实现直接遵循中间元素枚举策略。 y 上的循环确保我们只考虑有效的第二个朋友分配。 表达式`min(A, y - 1)`强制执行与第一个朋友的可用性和严格排序。 期限`C - y`隐式处理严格的不平等和赏金计数的上限，因为任何大于 C 的值都是无效的。 

需要注意边界条件。 当 y = 1 时，`y - 1`变为零，正确消除无效贡献。 当 y=C 时，`C - y`变为零，确保不会计算无效的 z 选择。

 ## 边缘情况

 当所有值都等于 1 时，循环仅计算 y = 1。在这种情况下，x 没有有效选择，z 也没有，因此贡献为零，符合不可能严格排序的要求。 

当 A 与 B 和 C 相比非常小时，例如 A = 1、B = 10、C = 10，大多数贡献消失，因为 x 始终为零（除了 y = 1 时除外），但这种情况也会失败，因为 z 要求 y < z。 该算法自然地通过最小和差异约束过滤这些情况。 

当 C 相对于 B 较小时，例如 C = 2 且 B 大，只有 y = 1 才有意义，但即便如此，z 的选择也会很快受到限制，并且总和会正确地折叠到零或一个非常小的数字，具体取决于 A。
