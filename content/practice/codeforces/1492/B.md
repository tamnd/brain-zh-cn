 ## 问题理解

 我们得到了一副牌`n`编号从 1 到 的不同卡片`n`，从下到上排列。 任务是构建一个具有尽可能高“顺序”的新牌组，该顺序是按牌值的加权和计算的，其中顶部牌的贡献更大。 唯一允许的操作是重复从原始牌堆顶部取出一定数量的牌并将它们放在新牌堆的顶部。 我们的目标是找到一系列这些操作来最大化牌组顺序。 

输入由多个测试用例组成。 每个测试用例都提供了牌组的大小`n`以及从下到上的卡牌值。 输出是新形成的牌组中从下到上的牌序列，产生最大顺序。 

约束条件允许`n`最多`10^5`每个测试用例和所有测试用例的总和`n`跨测试用例最多`10^5`。 由于时间限制为 1 秒，每个测试用例的复杂度高于 O(n) 的算法可能会变得太慢。 因此，任何重复迭代所有可能的子甲板的解决方案都是不切实际的。 

当最大的卡片已经接近底部时，就会出现微妙的边缘情况。 一次只拿一张卡的幼稚策略仍然有效，但可能会错过更大的重新排序机会。 例如，在甲板上`[1, 5, 2, 4, 3]`，如果我们一张一张地移动牌，最上面的`5`可能会延迟，从而减少套牌顺序。 正确的方法应该从顶部确定最大的连续牌块，其中包括当前最大的剩余牌，以便将其放在新牌组中的第一个位置。 

## 方法

 蛮力方法会尝试每一种可能的移动序列：对于每一个选择`k`，递归计算生成的新牌组并选择最大顺序。 这显然是不可行的，因为序列的数量呈指数增长`n`。 即使我们尝试每次只移动最上面的牌的贪婪方法，如果剩余的最大牌不在原始牌组的最顶部，它也会失败。 

关键的见解是，当剩余的最大牌在新牌组中尽可能高地出现时，顺序就会最大化。 因此，我们可以从原始牌堆的顶部开始扫描，始终寻找下一张最大的未使用的牌。 一旦找到它，我们就把它上面的所有牌（包括它本身）按顺序放入新牌组中。 这确保了首先放置最大值，并且连续的较小值保持其原始相对顺序，从而保留最大可能的加权和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最优贪心 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 对于每个测试用例，请阅读`n`以及从下到上的甲板。 由于操作是从顶部定义的，因此反转甲板以从上到下工作。 
2.初始化一个空列表`result`新牌组和指针`i`从原始牌组的顶部开始。 
3.同时`i`在甲板范围内：

 a. 找到位置`j`剩余的最大牌的数量从`i`到甲板的尽头。 

b. 从中取出连续的段`i`到`j`（包括）并将其附加到新牌组中。 

c. 移动`i`到`j + 1`。 
4. 处理完所有卡片后，反转`result`返回从下到上的输出顺序。 

为什么有效：在每一步中，我们都会确保最大的剩余牌尽早移至新牌组。 通过从当前顶部到这张卡的连续部分，我们保留了较小卡的相对顺序。 这种贪婪的选择最大化了最大值对最终加权和的贡献，并且最大的未放置的牌总是首先放置的不变性保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        deck = list(map(int, input().split()))
        deck.reverse()  # work from top to bottom
        result = []
        i = 0
        while i < n:
            # find the next largest remaining card
            max_card = max(deck[i:])
            j = i
            while deck[j] != max_card:
                j += 1
            # append all cards from i to j to result
            result.extend(deck[i:j+1])
            i = j + 1
        # convert back to bottom-to-top
        print(' '.join(map(str, result[::-1])))

if __name__ == "__main__":
    solve()
```该代码首先反转输入面板以简化从上到下的操作。 内循环定位剩余最大的牌，并将当前索引到这张牌的段按顺序移动到新的牌组中。 最后反转结果可以恢复正确的从下到上的顺序。 边缘情况（例如单张牌或已经下降的牌组）自然可以通过此过程处理。
