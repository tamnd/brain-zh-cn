 ## 解决方案
 ## 问题理解

 我们得到了一系列预定的旅行，每一次都描述了瓦西里必须出现在特定城市的几天间隔。 每个行程从开始日到结束日（含）全天都处于活动状态。 关键问题是，不同城市的重叠行程会产生冲突，因为瓦西里不能在同一天出现在两个不同的地方。 任务是确定此类冲突最早发生的日期，或报告从未发生过冲突。 

输入已按开始日期排序，这强烈表明应在单个前向传递中处理重叠，而无需重新访问较早的片段。 每个间隔可以与多个未来间隔重叠，因此我们维护的结构必须代表所有当前活动的行程。 

这些约束促使我们走向线性或接近线性的行为。 由于间隔多达 100,000 个，天数多达 1e9，任何模拟日常活动的方法都是不可能的。 即使扫描间隔内的所有日期也会太大，因为范围可能很大。 该解决方案必须隐式压缩时间线并且仅在间隔边界处做出反应。 

一些边缘情况值得关注。 首先，即使区间完全重叠，相同的城市也不会产生冲突。 例如，如果一次行程在城市 5 中为 [1, 10]，另一次行程也在城市 5 中为 [3, 7]，则不存在矛盾。 其次，多个重叠间隔可能只会在以后发生冲突，而不是在第一次重叠时发生冲突，因此我们必须连续跟踪活动集，而不是独立检查成对的交集。 第三，第一次冲突可能发生在较长时间间隔的中间，而不是在开始日，因此我们不能只比较端点。 

## 方法

 一种直接的方法是比较每对区间，检查它们是否重叠并且属于不同的城市。 如果两个区间重叠，我们计算交集并立即推断出该范围内存在冲突。 所有对中最早的此类交集给出了答案。 这是正确的，因为任何冲突都必定是由不同城市的某些重叠区间引起的。 

问题是效率。 对于 N 个间隔，有 O(N²) 对。 每次重叠检查都是恒定时间，但在最坏的情况下，当 N 为 100,000 时，这会导致大约 5e9 次操作，这远远超出了限制。 

关键的观察结果是间隔按开始日期排序。 这使我们能够按升序处理它们，并仅维护当前活动的间隔。 如果间隔尚未结束，则该间隔处于活动状态。 随着我们前进，结束日小于当前开始日的间隔可以被删除。 在所有活跃区间中，我们只需要知道它们属于哪个城市即可。 当新间隔与不同城市的活动间隔重叠时，就会发生冲突。 

我们不是单独跟踪所有活跃时间间隔，而是维护一个数据结构，记录当前活跃的城市及其最近结束日。 如果一个城市已经活跃，我们只会扩大其活跃范围。 如果另一个城市在与新间隔相交的时间处于活动状态，我们可以计算确切的重叠点并确定最早的冲突日。 

这将问题简化为从一个小的活动状态开始的间隔扫描线，而不是成对比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N²) | O(1) | O(1) | 太慢了 |
 | 主动跟踪扫地 | O(N log N) 或 O(N) | O(N) | 已接受 |

 ## 算法演练

1. 按开始日升序处理间隔，维护表示当前活动的所有间隔的结构。 这是有效的，因为一旦我们过了开始日，除了结束时间之外，任何较早的间隔都不会受到影响。 
2. 保存一个字典，将每个城市映射到其活动间隔的最大结束日。 如果同一城市的多个区间重叠，我们会将它们合并到一个活动范围中，因为它们不会产生冲突。 
3. 维护一个结构，使我们能够快速确定来自​​其他城市的所有活动间隔中的最早结束时间。 这是必要的，因为第一次冲突发生在最早的重叠边界处。 
4. 对于城市 c 中的每个新间隔 [l, r]，首先删除或终止其终点严格在 l 之前的所有活动间隔。 这些间隔不能与当前间隔重叠。 
5.检查当前所有与c不同的活跃城市。 如果任何这样的城市有一个结束时间至少为 l 的活动区间，则存在重叠。 最早的冲突日是 l 本身，因为新的间隔开始时另一个城市仍处于活动状态。 
6. 如果在开始处没有发现冲突，则通过将其活动结束更新为 max(current_end, r) 来插入或合并城市 c 的区间。 
7. 继续，直到处理完所有间隔。 如果没有发现冲突，则输出0。 

### 为什么它有效

 在任何时候，活动集都包含及时覆盖当前扫描位置的那些间隔。 由于间隔是按开始日期的升序处理的，因此可能与当前间隔冲突的任何间隔必须已经开始且尚未结束。 可能发生冲突的唯一方式是，如果两个不同的城市在某一天有重叠的活动覆盖范围，并且在处理导致重叠的后续间隔时会立即检测到这一点。 由于我们总是在插入新间隔之前检测到第一个此类重叠，因此第一个报告的日期全局最小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    active = {}  # city -> current end day
    
    earliest_conflict = None
    
    for _ in range(n):
        l, r, c = map(int, input().split())
        
        # expire outdated intervals
        to_remove = []
        for city, end in active.items():
            if end < l:
                to_remove.append(city)
        for city in to_remove:
            del active[city]
        
        # check conflict with other cities
        for city, end in active.items():
            if city != c and end >= l:
                if earliest_conflict is None:
                    earliest_conflict = l
                else:
                    earliest_conflict = min(earliest_conflict, l)
                break
        
        # merge current interval
        if c in active:
            active[c] = max(active[c], r)
        else:
            active[c] = r
    
    print(earliest_conflict if earliest_conflict is not None else 0)

if __name__ == "__main__":
    solve()
```该实现维护了当前活跃城市的字典。 每个步骤首先删除在当前开始之前结束的陈旧间隔，因为它们不能与任何未来间隔重叠。 然后，冲突检查会扫描剩余的活动条目，并检测是否有任何不同的城市在当前开始日仍然处于活动状态。 

合并步骤确保同一城市中的多个重叠区间不会单独累积，否则会不必要地膨胀活动集。 

最早的冲突记录在第一个检测到的重叠点。

 ## 边缘情况

 一种重要的边缘情况是两个区间在时间上重叠但属于同一城市。 用于输入`[1, 10, 1]`和`[2, 5, 1]`，活动结构保留单个条目`{1: 10}`合并后。 在处理第二个区间时，不存在不同的城市，因此不会触发冲突。 这证实了同城合并可以防止误报。 

另一种边缘情况是间隔在下一个间隔开始之前结束。 为了`[1, 2, 1]`其次是`[3, 4, 2]`，清理步骤在处理第二个间隔之前删除城市 1，因为它的结束时间小于下一个开始时间。 活动集变空，并且未检测到冲突。 

最后一个微妙的情况是多个城市以级联方式重叠。 如果间隔是`[1, 10, 1]`,`[2, 9, 2]`,`[3, 8, 3]`，由于城市 1 仍然处于活动状态，因此在第 2 天第二个时间间隔开始时检测到冲突。 该算法始终检测最早的此类边界，因为它会在每个新间隔进入活动时间线时检查重叠。
