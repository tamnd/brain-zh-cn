 ## 解决方案
 ## 问题理解

 我们正在使用一个无限网格，其中每个单元格都包含一个自然数，并以围绕中心单元格的扩展菱形层排列。 中央单元格包含值 1。从那里开始，数字逐层向外填充，每一层在前一层周围形成一个菱形（菱形）边界。 在每一层内部，填充从该层最顶层的单元开始，并顺时针方向进行，直到该层完成。 

我们没有得到网格，而是得到相对于中心的坐标。 中心单元被视为坐标 (0, 0)。 查询 (x, y) 要求输入单元格中写入的数字，即从中心向右 x 步，向上 y 步。 我们必须直接计算四个特定坐标对的该值，包括非常大的坐标对，例如（12345, 54321），这使得对网格的任何模拟完全不可行。 

尽管该问题只有四个查询，但坐标可能很大，这会立即排除任何显式构造层的尝试。 即使构建半径达到 50000 的层也已经涉及数十亿个单元，这超出了时间和内存限制。 任何解决方案都必须在少量算术推理之后在每个查询的恒定时间内计算出答案。 

一个常见的陷阱是像简单的曼哈顿距离映射那样假设对称性，或者尝试类似于方形网格的螺旋式公式。 这在这里失败了，因为菱形增长改变了层边界的结构：每层由 |x| 定义。 + |y|，而不是 max(x, y)。 另一个微妙的问题是编号的方向，因为从顶角开始顺时针遍历会引入偏移量，如果尝试直接重建位置，很容易错误计数。 

## 方法

 强力解释将明确模拟层的构造。 我们将从中心开始，逐层展开，并按顺时针顺序遍历每个菱形边界并分配编号。 对于点 (x, y)，我们将构造所有层，直到半径达到 |x| + |y|，然后通过跟踪遍历顺序索引到该层。 

这种方法是正确的，因为它准确地反映了定义。 然而，成本随着查询点的半径呈二次方增长。 对于像 (12345, 54321) 这样的坐标，层大小与 70000 成正比，并且每层包含 O(r) 边界元素，如果跨多个层简单地完成，则导致整体 O(r²) 构造。 这远远超出了可行的限度。 

关键的见解是网格不是任意的，它是曼哈顿距离的确定性分层。 每个点都位于由 d = |x| 确定的唯一菱形边界上 + |y|。 每层都有可预测的周长和可预测的起始索引。 一旦我们确定了该点位于菱形边界的哪一侧，我们就可以直接使用线性算术而不是模拟来计算其沿该边界的偏移。 

从强力解决方案到最优​​解决方案的转变是认识到每一层都是一个尺寸线性增长的循环，并且可以使用简单的案例分析将每个坐标映射到该循环上的位置，即它位于菱形的哪条边上。

 ## 算法演练

 我们独立处理每个查询。

1. 计算层索引 d = |x| + |y|。 这确定了该点位于哪个菱形边界上。 这样做的原因是相同曼哈顿距离的所有点都属于同一个菱形层。 
2. 计算第d层的起始层数。 每层有 8d 个单元（对于 d > 0），d 层之前的元素总数形成三角形累加。 可以导出为 1 + sum_{k=1}^{d-1} 8k = 1 + 4(d-1)d。 这给出了层 d 边界上的第一个数字。 
3. 确定该点位于菱形边界的哪四个边上。 菱形有四个有向边，每条边对应 (x, y) 空间中的一条线性线段：

 - 右上角，其中 y = d 并且 x 从 0 移动到 d
 - 右下侧，其中 x = d 且 y 从 0 移动到 -d
 - 左下侧，其中 y = -d 并且 x 从 d 移动到 -d
 - 左上角，其中 x = -d 并且 y 从 -d 移动到 d
 4. 将 (x, y) 转换为沿其对应边的偏移量。 除角点外，每条边都贡献 2d 步长，我们计算从该边的起始顶点开始的位移。 
5.将此偏移量添加到第d层的起始值以获得最终答案。 

### 为什么它有效

 该结构保证每一层都是一个具有固定线性顺序的简单闭环。 由于每个坐标恰好属于一层并且恰好属于该层的一个边缘，因此从 (x, y) 到沿循环的位置的映射是单射的。 前缀和公式确保我们知道循环的确切起始标签，边分解确保确定性偏移。 没有两个不同的坐标映射到同一位置，因为每个边界段除了端点之外都是不相交的，并且端点是按遍历顺序一致分配的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve(x, y):
    d = abs(x) + abs(y)
    
    if d == 0:
        return 1
    
    start = 1 + 4 * (d - 1) * d
    
    if y == d:
        offset = x
    elif x == d:
        offset = d + (d - y)
    elif y == -d:
        offset = 3 * d + (d - x)
    else:
        offset = 4 * d + (y + d)
    
    return start + offset

# fixed queries from statement
queries = [
    (3, 2),
    (0, 10),
    (12, 0),
    (12345, 54321)
]

out = []
for x, y in queries:
    out.append(str(solve(x, y)))

print(" ".join(out))
```该实现首先按曼哈顿半径对查询进行分类，这确定了菱形层。 基值计算使用边界大小的算术级数的封闭形式，避免任何模拟。 

条件结构是菱形四个边的直接编码。 每个分支对应于从顶部顶点开始按顺时针顺序沿着菱形的一侧行走。 一个常见的实施错误是混淆了每条边上的遍历方向，这导致整条边上的一致偏移。 另一个常见错误是忘记角点在概念上属于两条边，但在遍历顺序中仅分配给一个线段。 

## 工作示例

 我们追踪两个有代表性的点。 

### 示例 1：(x, y) = (0, 10)

 我们计算 d = |0| + |10| = 10。这会将点放在第 10 层上。该层的起始值为：

 | 步骤| 价值|
 | ---| ---|
 | d | 10 | 10
 | 开始 | 1 + 4·9·10 = 361 |

 由于 x = 0 且 y = d，因此该点位于顶部边缘。 偏移量为 x = 0。 

最终答案是361。 

这证实了每层的最顶端点正是该层的起点。 

### 示例 2：(x, y) = (12, 0)

 我们计算 d = 12。起始值为：

 | 步骤| 价值|
 | ---| ---|
 | d | 12 | 12
 | 开始 | 1 + 4·11·12 = 529 |

 这里 y = 0，所以我们位于右下或左下边界，具体取决于符号。 由于 x = d，因此这是右下边缘。 

偏移量 = d + (d - y) = 12 + 12 = 24。 

最终答案是 529 + 24 = 553。 

这显示了水平边缘如何在垂直遍历开始之前引入完整的段移位。

 ## 边缘情况

 对于中心单元 (0, 0)，算法无需输入任何边缘逻辑即可正确返回 1。 这避免了层计算中未定义的行为，因为 d 变为 0 并单独处理。 

对于恰好位于轴边界上的点（例如 (d, 0) 或 (0, d)），分类仍将它们确定性地分配给单个边。 例如，在 (5, 0) 处，我们得到 d = 5 且 x = d，因此该点位于右下边缘。 偏移公式可确保共享角点处不会出现歧义，因为遍历顺序将角点恰好分配给一个线段。 

对于像 (12345, 54321) 这样的大坐标，计算保持稳定，因为它在中间步骤中仅使用最多 10^9 左右的整数相乘，完全在 Python 的安全整数范围内。
