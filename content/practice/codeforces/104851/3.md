 ## 解决方案
 ## 问题理解

 我们被要求计算仅使用三个字符可以形成多少个有效字符串：`a`,`o`， 和`c`，有两个约束。 每个字符串必须有固定长度`N`，并且任何字符都不允许出现超过`K`单个字符串内的时间。 

因此，我们只计算那些出现频率的字符串，而不是不受限制的字符串。`a`,`o`， 和`c`保持在限制范围内`K`，而字符总数正好是`N`。 

考虑输出的一个有用方法是我们计算所有分配方式`N positions`在对应于三个字母的三个箱中，然后计算每个分布产生多少个不同的排列。 仅当没有任何 bin 超过大小时，分布才有效`K`。 

的价值观`N`和`K`在这个问题中，它们非常小，固定为四个查询，最大的情况是`N = 20`。 这立即排除了对大范围渐近优化数据结构或 DP 的任何需要。 直接组合枚举是可行的，因为有效频率三元组的状态空间很小。 

生成所有字符串并检查有效性的天真尝试在概念上是可行的，但即使对于`N = 20`因为它会探索`3^20`的可能性，这远远超出了所需要的。 

这里经常出现的一个实现错误是忘记约束是每个字符的，而不是全局的。 例如，对于`N = 4, K = 3`，像这样的字符串`aaaa`即使只使用一个字符也是无效的，因为它超出了限制`a`，而字符串像`aaao`是有效的。 

如果试图在不固定频率三元组的情况下枚举排列，另一个微妙的问题是重复计算，因为不同的排列对应于相同的多集配置，并且必须单独计数。 

## 方法

 暴力方法构造每个可能的长度字符串`N`超过三个字母并检查每个字母是否遵守频率限制。 这是可行的，因为每个字符串都是独立验证的，但它会扩展为`3^N`候选人。 为了`N = 20`，这大约是 34 亿个字符串，即使在考虑验证之前，这个数字也太大了。 

关键的观察是具有相同频率计数的字符串贡献相等并且可以分组。 我们不需要显式地构建字符串，而只需选择每个字符出现的次数。 如果`a`出现`i`次，`o`出现`j`次，以及`c`出现`k`次，那么我们必须有`i + j + k = N`他们每个人最多`K`。 对于每个有效三元组，字符串的数量就是多项式系数`N! / (i! j! k!)`。 

这将问题减少到迭代所有有效的整数三元组`(i, j, k)`在有界范围内并对组合值求和。 自从`N ≤ 20`，这样的三元组的数量最多约为 231 个组合，这是微不足道的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解字符串 | O(3^N) | O(3^N) | O(N) | 太慢了 |
 | 频率枚举| O(K^2)（以 N 为界）| O(1) | O(1) | 已接受 |

 ## 算法演练

 我们通过枚举有效的频率分配来计算答案。 

1. 固定一个值`i`对于数量`a`字符来自`0`到`K`，因为任何有效的解决方案都不能超过每个字母的上限。 这限制了搜索空间的一个维度。 
2. 固定一个值`j`对于数量`o`人物，再次来自`0`到`K`。 此时，强制剩余计数。 
3. 计算`k = N - i - j`，代表有多少个`c`需要字符来完成字符串。 这避免了第三次循环并确保我们始终遵守总长度约束。 
4. 检查是否`k`位于内`[0, K]`。 如果不是，则该频率三元组无效并且没有任何贡献。 
5. 对于每个有效的三元组`(i, j, k)`，计算多项式系数`N! / (i! j! k!)`，它计算具有这些频率的多重集的不同排列的数量。 
6. 将这些值累加成一个累加值，这就是最终的答案。 

### 为什么它有效

 每个有效字符串恰好对应一个频率三元组`(i, j, k)`。 每个三元组准确地贡献了该多重集的不同排列的数量。 枚举涵盖了所有可行的三元组，没有重叠，因此每个有效字符串都只计算一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from math import factorial

def solve():
    N, K = map(int, input().split())
    ans = 0

    for i in range(K + 1):
        for j in range(K + 1):
            k = N - i - j
            if 0 <= k <= K:
                ans += factorial(N) // (factorial(i) * factorial(j) * factorial(k))

    print(ans)

solve()
```实现直接遵循组合解释。 嵌套循环枚举`i`和`j`， 尽管`k`是为了避免不必要的迭代而推导的。 基于阶乘的多项式计算是安全的，因为`N`最多为 20，因此所有值都保持很小并且整数算术是精确的。 

一个常见的错误是迭代`k`独立地，这引入了冗余检查并增加了循环复杂性，但没有任何好处。 另一个潜在的陷阱是在循环内重复重新计算阶乘； 在这里，由于微小的限制，它是可以接受的，但在问题的更大版本中，预计算是必要的。 

## 工作示例

 我们追踪两个代表性案例的逻辑。 

### 示例 1：N = 3，K = 1

 我们只允许每个角色最多出现一次。 

| 我| j | k = 3 - i - j | k = 3 - i - j | 有效| 贡献|
 | ---| ---| ---| ---| ---|
 | 0 | 0 | 3 | 没有 | - |
 | 0 | 1 | 2 | 没有 | - |
 | 0 | 2 | 1 | 没有 | - |
 | 0 | 3 | 0 | 没有 | - |
 | 1 | 0 | 2 | 没有 | - |
 | 1 | 1 | 1 | 是的 | 3！ = 6 |

 仅有的`(1,1,1)`有效，产生`6`排列，匹配所有排列`a`,`o`,`c`。 

### 示例 2：N = 4，K = 3

 我们仅排除字母出现 4 次的情况。 

有效配置包括所有三元组之和为 4，除了`(4,0,0)`,`(0,4,0)`,`(0,0,4)`。 

总计为`3^4 = 81`减去三个无效的统一字符串，得到`78`。 

这显示了约束如何仅删除极端配置，同时保持大部分组合空间完好无损。

 ## 边缘情况

 当出现一种边缘情况时`K >= N`。 在这种情况下，约束变得无关紧要，因为没有字母可以超过`N`无论如何发生。 该算法自然地处理这个问题，因为所有三元组总和为`N`被接受，并且多项式和崩溃为`3^N`。 

例如，与`N = 3, K = 3`, 每个三元组`(i, j, k)`总和为 3 有效。 该算法枚举所有这些并产生`27`，匹配 3 个字母字母表上的完整字符串集。 

另一种边缘情况发生在`K = 0`。 这里只有空赋值才是有效的，但是因为`N > 0`，没有三元组可以满足`i + j + k = N`，所以答案就变成了`0`。 在这种情况下，枚举正确地生成没有有效的配置。
