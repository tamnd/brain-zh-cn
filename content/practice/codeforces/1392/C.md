 ## 解决方案
 ## 问题理解

 我们得到了从左到右排列的一系列高度。 目标是修改此序列，使其变为非递减序列，这意味着每个元素至少与其前面的元素一样大。 

唯一允许的操作有点不寻常：我们选择一个连续的位置块，其高度已经不减少，并且我们将该块中的每个值都增加一。 我们可以根据需要多次重复此操作，并且希望最大限度地减少使整个数组不减所需的操作次数。 

这里最重要的约束是所有测试用例的长度总和，最多 200,000 个。 这迫使每个测试用例都有一个基本上线性或接近线性的解决方案。 任何显式模拟操作或尝试重复修复段的方法都会失败，因为每个操作可能影响许多元素，并且操作数量也可能很大。 

当局部重叠减少时，就会出现一个微妙的问题。 例如，在像这样的数组中`5 1 4 2`，一个天真的想法可能会尝试独立地修复每个反转，但操作是相互作用的，因为增加一个区域可以在其他地方创建或消除单调性。 另一种故障模式是假设我们总是在最大非递减段上进行操作，这并不总是最佳的，因为可能需要选择较小的段以避免破坏其他地方的结构。 

## 方法

 强力策略会尝试模拟该过程：重复扫描数组，找到任何非递减的子段，应用增量，然后重复直到排序。 这在原则上是正确的，因为每个操作都遵守约束。 然而，每次操作仅将值加一，并且最多可以有 O(max(a)) 有效增量层。 在最坏的情况下，高度相差高达 10^9，这使得这完全不可行。 

关键的观察是，我们应该停止考虑实际操作，而应该考虑每个位置相对于其邻居需要多少“修正层”。 当我们从左到右扫描时，每当数组从`a[i-1]`到`a[i]`，后缀开始于`i`最终必须提高到至少与该下降所造成的赤字相匹配。 每一次下降都会贡献一个独立的“高度校正需求”，并以结构化的方式累积。 

这导致了贪婪的累积：我们维护到目前为止需要多少次操作，每当我们看到减少时，我们必须在累积意义上将答案增加该减少的大小。 令人惊讶的简化是，答案变成了连续元素之间的正差之和，但以特定的方向方式计算：由于我们强制执行非递减顺序，因此我们只关心从左到右移动时序列违反单调性的地方。 

暴力破解会失败，因为它是根据显式运算进行推理的。 最佳解决方案之所以有效，是因为每次减少都会独立地影响所需的全局“提升层”的最小数量。

 ## 算法演练

 我们从左到右处理数组，同时维护需要多少操作才能确保所有先前的元素可以与非递减结构保持一致。 

1.从计数器开始`ans = 0`。 这将存储所需操作的数量。 
2. 从索引 1 到 n-1 迭代数组。 在每个位置，将当前高度与前一个高度进行比较。 
3.如果`a[i] >= a[i-1]`，在这个边界上没有任何结构被破坏，因此这对不会强制执行新的操作。 
4. 如果`a[i] < a[i-1]`，序列下降。 这意味着后缀始于`i`相对于之前的值太低，因此需要进行额外的操作。 我们增加`ans`经过`a[i-1] - a[i]`。 

此增量正确的原因是，每个减少单位对应于一个所需的“层”，该“层”随后必须应用于覆盖该后缀的非减少段。 由于操作可以将任何非减子数组加 1，因此每个单位间隙在最佳构造中恰好贡献了一个必要的操作。 

### 为什么它有效

 每次序列下降时，我们都会引入一个缺陷，必须通过应用于包含较小元素的后缀的未来操作来补偿该缺陷。 由于操作只能在单调段上均匀地增加值，因此我们无法通过单个单位增加来修复多个独立的下降，除非它们以一致的方式对齐。 贪婪累积确保每个赤字单位只计算一次，并且不会在已经平衡的区域上浪费任何操作。 

这将问题转化为测量相邻对之间的总向下“压力”，这直接对应于所需的全局增量层的最小数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ans = 0
        for i in range(1, n):
            if a[i] < a[i - 1]:
                ans += a[i - 1] - a[i]
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```代码直接实现了前面介绍的从左到右的累加。 唯一的微妙之处是确保我们只在发生严格减少时才增加贡献； 相等或递增的转换不需要校正，因为它们已经局部满足非递减结构。 

每个测试用例都会累积答案并在最后打印以提高效率。

 ## 边缘情况

 一个关键的边缘情况是完全非增数组，例如`5 4 3 2 1`。 该算法对每个相邻的水滴求和，产生`1 + 1 + 1 + 1 = 4`加上初始差异累计为 10，这与每一步都会引入新的所需校正层的事实相匹配。 

另一种情况是一个已经非递减的数组，例如`1 2 2 3`。 由于没有减少，因此循环永远不会增加答案，并且输出为 0。这证实了该算法不会过度计算平坦段。 

一个更微妙的情况是交替的峰值，例如`3 1 4 1 5 1`，其中掉落发生在多个独立位置。 每个丢弃都是单独计数的，这表明该算法将每个本地违规视为所需操作的独立来源，这正是操作定义所强制执行的。
