 ## 解决方案
 ## 问题理解

 每个玩家坐在一个圆圈上，攻击他们的两个邻居之一。 我们得到一个由以下组成的循环串`L`和`R`。 

如果玩家`i`剩下的攻击，我们写`L`。 如果他们攻击正确，我们会写`R`。 

根据游戏规则，玩家被认为是有逻辑的：

 - 如果恰好有一个邻居攻击他们，他们必须反击那个邻居。 
- 如果零个或两个邻居攻击它们，则任一攻击方向都是可接受的。 

我们可以翻转任何玩家的选择`L`到`R`或来自`R`到`L`。 每个翻转的玩家花费一次操作。 我们必须找到所需的最少翻转次数，以便每个玩家都变得有逻辑。 

第一个挑战是理解逻辑最终配置是什么样的。 

假设我们观察一名攻击方向与其邻居不同的玩家。 例如，边界`RL`出现。 左边的玩家攻击右边，右边的玩家攻击左边，所以他们互相攻击。 这样的立场已经完全一致了。 

有趣的部分是在相同字符的最大块内发生的情况：```
RRRRR
```或者```
LLLL
```在这样的区域内，中间球员是有问题的。 他们只收到一次传入攻击，但不会反击，因此需要进行一些更改。 

制约因素很大。 所有字符串的总长度最多为`2·10^5`，并且可能最多有`10^4`测试用例。 任何检查所有可能的翻转组合的解决方案都是不可能的。 甚至一个`O(n²)`算法将执行大约`4·10^10`最坏情况下的操作。 我们需要一个线性解。 

一些边缘情况很容易被忽略。 

考虑：```
n = 5
RRRRR
```因为绳子是圆形的，所以这是长度为 5 的一串，而不是五个单独的位置。 忘记圆的线性运行处理算法会计算出错误的答案。 

另一个例子是：```
RLRLRL
```每个玩家都已经反击了攻击他们的独特玩家。 答案是`0`。 

第三个微妙的情况是：```
RRRLLL
```仅当第一条和最后一条具有相同字符时，它们才会接触圆形边界。 这里没有，所以实际上有两个长度为 3 的独立游程。将字符串视为一个合并游程是不正确的。 

## 方法

 暴力方法会尝试每个玩家子集进行翻转并检查结果配置是否合乎逻辑。 有`2^n`可能的翻转模式，即使对于`n = 40`，更不用说`n = 200000`。 

为了获得有用的东西，我们需要了解有效配置的结构。 

查看相同字符的最大运行次数：```
RRRRRR
```考虑跑动中连续的三名球员。 中间玩家仅受到一侧的攻击。 由于他们的攻击方向与其他人相同，因此他们不会反击。 这样的玩家就违反了规则。 

改变一名球员的方向最多可以在一场比赛中修复三个连续的位置。 这导致了一种熟悉的模式：三个相等连续方向的每个块都需要一次修改。 

对于长度的线性运行`k`，最少的变化次数为：```
k // 3
```这与许多“突破长跑”问题中使用的计数参数完全相同。 

唯一的复杂之处是圆形结构。 

如果整个圆圈由单个字符组成，例如：```
RRRRRRR
```只有一游长度`n`，答案是：```
(n + 2) // 3
```否则，至少存在一个相邻字符不同的边界。 这样的边界自然就打破了圆圈。 一旦我们在字符不同的任意位置切圆，问题就变成了线性。 然后可以独立处理每个最大运行，从而贡献`length // 3`。 

这产生了一个简单的线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2ⁿ·n) | O(2ⁿ·n) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 检查循环字符串中的所有字符是否相同。 

如果是，则整个圆形成一圈长度`n`。 答案是`(n + 2) // 3`。 
2. 否则，找到相邻字符不同的任何位置。 

这样的位置始终存在，因为并非所有字符都是平等的。 
3. 概念性地旋转圆，使该位置成为起点。 

在此剪切之后，结果序列的第一个和最后一个字符不同，这意味着不再有边界环绕。 
4. 遍历旋转序列并计算每个最大相同字符串的长度。 
5. 对于每个长度`len`， 添加`len // 3`到答案。 

一次运行中每三个连续的相同方向需要翻转一次，并且这些要求在运行之间是独立的。 
6. 输出累计答案。 

### 为什么它有效

 当跑步有长度时`len`，除了边界附近的玩家之外，每个玩家的行为都是相同的。 有问题的位置出现在三个连续相同方向的组中。 一个精心挑选的翻转最多可以修复一个这样的组，所以至少`len // 3`翻转是必要的。 

相反，在运行中每隔三个位置进行一次翻转可以准确地实现`len // 3`改变并使所有玩家都合乎逻辑。 由于不同的运行因方向变化而分开，因此它们的修正不会相互作用。 求和`len // 3`在所有运行中给出全局最优值。 

对于整个圆为一圈的特殊情况，不存在自然边界。 循环长度`n`需要`ceil(n/3)`变化，等于`(n + 2) // 3`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        s = input().strip()

        if s.count(s[0]) == n:
            print((n + 2) // 3)
            continue

        pos = 0
        while s[pos] == s[(pos + 1) % n]:
            pos += 1

        s = s[pos + 1:] + s[:pos + 1]

        ans = 0
        cnt = 1

        for i in range(1, n):
            if s[i] == s[i - 1]:
                cnt += 1
            else:
                ans += cnt // 3
                cnt = 1

        ans += cnt // 3
        print(ans)

solve()
```第一个分支处理整个循环是单次运行的特殊情况。 在这种情况下，标准游程分解不起作用，因为没有不同的边界可供切割。 

对于所有其他情况，我们找到具有不同字符的任何相邻对。 在这样的一对之后立即切割可确保旋转字符串的第一个和最后一个字符不同。 这将圆形运行结构转换为普通的线性运行结构。 

遍历使用标准计数器计算最大游程长度。 每当运行结束时，我们添加`run_length // 3`到答案。 循环结束后，还必须处理最终的运行。 

一个常见的错误是忘记了所有平等的情况。 如果不进行特殊处理，旋转步骤将无法找到有效的切割，并且公式将变得不正确。 

另一个容易犯的错误是在任意位置进行切割。 如果切口位于运行内，则循环运行可能会分成两个较小的运行，从而导致计数不足。

 ## 边缘情况

 考虑：```
n = 5
RRRRR
```该算法检测到每个字符都是相同的。 它立即返回：```
(5 + 2) // 3 = 2
```不尝试旋转。 这可以避免我们永远搜索不同的边界时发生的失败。 

现在考虑：```
n = 6
RRRLLL
```弦不均匀。 第三种之间存在不同的界限`R`首先`L`。 

运行分解变为：```
RRR
LLL
```贡献是：```
3 // 3 + 3 // 3 = 2
```给出正确答案`2`。 

最后，考虑：```
n = 8
RLRLRLRL
```每次跑步都有长度`1`。 

该算法计算：```
1 // 3 + 1 // 3 + ...
```总和为`0`。 

这证实了已经有效的配置被识别而无需任何不必要的修改。
