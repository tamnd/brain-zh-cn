 ## 解决方案
 ## 问题理解

 我们在数轴上得到两个点的集合。 第一个系列由具有职位的面包店组成$x_1, x_2, \dots, x_N$。 第二个由带有职位的邮箱组成$y_j$，每个也承载着一个重量$k_j$代表西拉诺访问该邮箱时遇到的其他敌人。 

Cyrano 必须从每个面包店开始执行一次行程。 对于位置的面包店$x_i$，他选择任意邮箱$y_j$来参观。 选择邮箱的成本$j$来自面包店$i$有两个组成部分： 旅行费用$x_i \cdot y_j$，以及额外的固定成本$k_j$免得在那个邮箱里与求婚者战斗。 目标是为每个面包店分配一个邮箱，以便最大限度地减少所有选择的总成本。 

因此，任务简化为每个人独立地进行选择$x_i$, 邮箱索引$j$最小化$x_i y_j + k_j$，并对所有面包店进行总结。 

限制因素$N, M \le 10^5$立即排除检查所有对$(i, j)$，这将是$10^{10}$运营。 任何解决方案都必须利用线性表达式中的结构$x_i y_j + k_j$以避免每对评估。 

微妙的边缘情况来自零值。 如果$x_i = 0$，则成本降低为$k_j$，意味着只有邮箱权重很重要。 如果全部$y_j = 0$，那么所有的面包店都会选择邮箱数量最少的$k_j$。 忽略零处理或假设斜率严格为正的简单实现仍然可以在数学上起作用，但如果不正确地修剪候选者，通常会失败。 

另一个陷阱是假设同一个邮箱对于所有面包店都是最佳的。 最优的$j$取决于$x_i$，所以全局最小值$k_j$或者$y_j$仅靠这一点是不够的。 

## 方法

 暴力解决方案评估每一对$(i, j)$, 计算$x_i y_j + k_j$并取每个最小值$i$。 这是正确的，因为它直接遵循问题的定义。 然而，它需要$O(NM)$评价，达到$10^{10}$在最坏的情况下操作是不可行的。 

关键的观察结果是对于固定邮箱$j$，成本函数为$x$是线性的：$$f_j(x) = x \cdot y_j + k_j$$每个邮箱定义一行。 对于每个面包店价值$x_i$，我们想要所有线上的最小值$x_i$。 这正是一个动态凸包技巧查询问题：我们静态添加了行，并且查询了许多行$x$- 坐标。 

然而，还有一个额外的简化。 我们不需要动态维护线路； 我们可以按斜率排序$y_j$并构建一个凸包线。 斜率是静态的，因此我们可以对所有线进行一次预处理并有效地回答所有查询。 

由于查询未排序，我们可以按以下方式对面包店进行排序$x_i$，按升序处理它们，并在凸包上维护一个指针，以在摊余常数时间内回答每个查询。 

整体结构变成：构造一个按斜率排序的线的下凸包，然后按升序扫描查询$x_i$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(NM)$|$O(1)$| 太慢了|
 | 凸包技巧 |$O((N+M)\log M)$或者$O(N+M)$|$O(M)$| 已接受 |

 ## 算法演练

 我们解读每个邮箱$j$作为一条有斜率的线$y_j$并拦截$k_j$，以及每家面包店$i$作为查询点$x_i$。 

### 1. 按斜率对邮箱行进行排序

 我们按升序对邮箱进行排序$y_j$。 这确保了当我们构建凸包时，斜率以单调顺序处理，这对于有效保持凸性是必要的。 

### 2. 构建线的下凸包

 我们迭代排序的邮箱并维护一堆候选行。 对于每个新行，如果最后一行与所有将来的查询无关，我们会从堆栈中删除最后一行。 这是通过船体中最后两条线与新线之间的交集比较来检查的。 

这样做的原因是任何线对于任何线来说都不是最小的$x$可以安全地丢弃。 

### 3. 将面包店作为查询进行处理

 我们对面包店进行排序$x_i$。 对于每个$x_i$，我们维护一个指向凸包的指针。 作为$x_i$增加时，最优线索引沿着船体单调移动。 

我们评估成本$x_i y_j + k_j$仅适用于当前最佳行，如果下一行给出较小的值，则可能会前进指针。 

### 4. 累积答案

 对于每个面包店，我们将找到的最佳成本添加到总和中，并取模$10^9+7$。 

### 为什么它有效

 每个邮箱定义一个线性函数，问题就简化为在一组行上取逐点最小值。 这些线的下包络线充分表征了所有最佳选择。 对斜率和查询进行排序使我们能够利用单调性：一旦一条线不再是最佳的，对于更大的线来说，它永远不会再次成为最佳$x$。 这保证了每行最多添加和删除一次，并且每个查询最多将指针前进一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def bad(l1, l2, l3):
    # check if l2 is unnecessary between l1 and l3
    # (k2 - k1)/(y1 - y2) >= (k3 - k2)/(y2 - y3)
    y1, k1 = l1
    y2, k2 = l2
    y3, k3 = l3
    return (k2 - k1) * (y2 - y3) >= (k3 - k2) * (y1 - y2)

def eval_line(line, x):
    y, k = line
    return y * x + k

def solve():
    N, M = map(int, input().split())
    x = [int(input()) for _ in range(N)]
    mail = [tuple(map(int, input().split())) for _ in range(M)]

    mail.sort()  # sort by slope y

    # build convex hull
    hull = []
    for line in mail:
        while len(hull) >= 2 and bad(hull[-2], hull[-1], line):
            hull.pop()
        hull.append(line)

    # queries sorted
    queries = sorted(x)

    ans = 0
    j = 0

    for xi in queries:
        while j + 1 < len(hull) and eval_line(hull[j + 1], xi) <= eval_line(hull[j], xi):
            j += 1
        ans = (ans + eval_line(hull[j], xi)) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```该实现将邮箱预处理与面包店查询分开。 这`bad`函数在使用交叉乘法构造船体时删除冗余行以避免浮点除法。 

指针`j`只会向前移动，因为排序查询保证了最佳行索引的单调性。 这是线性查询处理的关键。 

一个微妙的问题是乘法可以超过 32 位范围，因此 Python 的任意精度可以安全地处理它，但在更严格的语言中，需要 128 位整数。

 ## 边缘情况

 当所有$x_i = 0$，成本变得与斜率无关，并减少到选择最小的$k_j$对于每家面包店。 该算法仍然可以处理这个问题，因为所有线都会评估其截距，并且船体将最小截距线保持在$x = 0$。 

当所有$y_j = 0$，每条线都是常数。 船体减少到最小线$k_j$，并且每个查询返回相同的值。 指针逻辑永远不会中断，因为所有计算都一致。 

当有多个坡度相同的邮箱时$y_j$，只有最小的一个$k_j$在船体结构中幸存下来。 这`bad`检查确保删除多余的线路，防止错误的支配。 

什么时候$x_i$值未排序，排序确保了船体的单调遍历。 如果不进行排序，指针移动可能会变得不单调并破坏摊销保证，从而导致重复扫描。
