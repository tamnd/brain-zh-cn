 ## 解决方案
 ## 问题理解

 我们正在维护一个堆栈网格。 的每个单元格$N \times N$板上包含一叠垂直的字母。 该系统支持随时间推移应用的三种操作：将字母推入堆栈、从堆栈中弹出顶部字母以及查询给定字母是否是特定堆栈中的“多数”。 

对于一封信来说，一叠被认为是美丽的$c$如果在当前该单元格堆栈中的所有字母中，出现的次数$c$严格大于堆叠高度的一半。 每个查询都会询问某个特定的字母当时是否是堆栈中的大多数。 

关键的挑战是运营是完全动态的。 推送和弹出与查询交错，每个单元格独立运行。 自从$Q$可以达到$2 \cdot 10^5$，我们需要每个操作的效率接近$O(1)$或者$O(\log N)$每个堆栈更新。 

一个天真的解释是显式维护每个堆栈，并且对于每个查询，扫描整个堆栈以计算给定字母的出现次数。 这立即导致$O(Q^2)$如果单个堆栈变大，最坏情况下的行为。 

当在空堆栈上发出弹出操作时，会出现微妙的边缘情况。 这些必须被默默地忽略，这意味着我们不能假设堆栈总是存在或非空。 

另一个边缘情况是在同一单元上交替查询和更新。 如果假设堆栈摘要在弹出后仍然有效，则幼稚的缓存策略可能会失败。 

失败场景示例：如果我们维护计数但忘记在弹出时正确递减，则查询可能会在删除后错误地报告多数。 

## 方法

 暴力破解的想法很简单：将每个堆栈存储为字符列表。 如果可能的话，推送会追加，弹出会从末尾删除，查询会迭代堆栈，计算所请求字母的出现次数。 这是正确的，但是每次查询都会花费$O(h)$， 在哪里$h$是堆栈高度。 如果所有操作都针对同一个单元格，则总成本变为$O(Q^2)$，这太慢了。 

为了改进，我们观察到每个堆栈独立发展，只有两个操作改变它：从顶部推送和弹出。 这正是具有撤消功能的序列上的动态多重集。 我们只需要知道每个字母在当前操作前缀中的频率。 

我们不必重新计算每个查询的计数，而是为每个单元格维护一个超过 26 个字母的频率表和当前堆栈大小。 如果堆栈非空，则压入会增加一个字母的数量和大小，而弹出则会减少一个字母的数量和大小。 查询变成恒定时间检查：将查询字母的频率与堆栈大小的一半进行比较。 

这减少了每次操作$O(1)$，因为字母大小是恒定的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(Q \cdot H)$|$O(Q)$| 太慢了|
 | 最佳（每个堆栈的频率）|$O(Q)$|$O(N^2 \cdot 26)$| 已接受 |

 ## 算法演练

 我们为每个单元维护两个结构：字母堆栈和大小为 26 的频率数组，跟踪堆栈中当前每个字母的计数。 

1. 初始化一个$N \times N$网格，其中每个单元格都有一个空列表和一个零初始化的频率数组。 这确保每个操作都有一个定义的起始状态。 
2. 对于单元格的推送操作$(x, y)$，将字母附加到堆栈并增加其频率。 这使频率表与实际堆栈内容保持同步。 
3. 对于弹出操作$(x, y)$，首先检查栈是否非空。 如果是，则删除顶部元素并减少其频率。 如果为空，则不执行任何操作，因为没有要删除的元素。 
4. 查询：$(x, y)$带信$c$，计算堆栈大小并比较$2 \cdot \text{freq}[c]$与堆栈大小。 如果严格大于则输出“yes”，否则输出“no”。 

乘法避免了浮点除法并确保整数安全比较。 

### 为什么它有效

 在每一步中，频率数组都与堆栈中当前的多组元素完全匹配，因为每次入栈都恰好增加一个计数，而每次有效的弹出都恰好减少一个计数。 如果没有相应的堆栈修改，则任何操作都不会修改计数，因此在操作序列上归纳地保持了一致性。 由于多数条件仅取决于计数和总大小，因此查询检查始终等同于定义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def idx(c):
    return ord(c) - 97

def solve():
    N, Q = map(int, input().split())
    
    grid_stack = [[[] for _ in range(N)] for _ in range(N)]
    grid_cnt = [[[0]*26 for _ in range(N)] for _ in range(N)]
    
    out = []
    
    for _ in range(Q):
        tmp = input().split()
        if not tmp:
            continue
        
        t = int(tmp[0])
        
        if t == 0:
            c = tmp[1]
            x = int(tmp[2])
            y = int(tmp[3])
            
            grid_stack[x][y].append(c)
            grid_cnt[x][y][idx(c)] += 1
        
        elif t == 1:
            x = int(tmp[1])
            y = int(tmp[2])
            
            if grid_stack[x][y]:
                c = grid_stack[x][y].pop()
                grid_cnt[x][y][idx(c)] -= 1
        
        else:
            c = tmp[1]
            x = int(tmp[2])
            y = int(tmp[3])
            
            size = len(grid_stack[x][y])
            cnt = grid_cnt[x][y][idx(c)]
            
            if cnt * 2 > size:
                out.append("yes")
            else:
                out.append("no")
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案为每个单元保留一个显式堆栈，以便弹出操作有效并始终删除正确的字母。 频率数组与堆栈更改同步更新，这一点至关重要，因为查询仅依赖于聚合计数，而不依赖于顺序。 

大多数检查使用`cnt * 2 > size`以避免分裂问题。 当大小为奇数时，这一点至关重要，因为否则整数除法会丢失精度。 

通过在弹出之前检查堆栈是否存在来显式保护空弹出情况，确保不会发生索引错误。

 ## 边缘情况

 一个重要的边缘情况是从空堆栈中重复弹出。 由于必须忽略该操作，因此频率数组必须保持不变。 例如，从空单元格开始并发出多次弹出操作必须保持状态不变，从而为以后的查询保留正确性。 

另一种情况是一叠尺寸为一的情况。 如果出现一个字母，则始终是绝对多数。 该算法自然地处理这个问题，因为`cnt * 2 > size`变成`2 > 1`。 

最后一个微妙的情况是不同字母之间的快速交替。 由于每次更新仅涉及一个频率槽和堆栈，因此频率与堆栈内容匹配的不变性确保即使是对抗性序列也不会导致状态不同步。
