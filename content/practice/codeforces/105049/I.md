 ## 解决方案
 ## 问题理解

 我们将从 1 到 n 的所有整数排列成一个排列，其中每个整数代表一场比赛，它的值代表它的好坏。 小数字是更好的玩法，大数字是更差的玩法。 目标是计算有多少排列产生有限的“失望分数”。 

当 i 处的表现严格地比两个相邻位置差时，排列中的位置 i 就会令人失望，这意味着它的值大于两个相邻值。 换句话说，它是严格的局部最大值。 每个这样的位置都会对总分贡献其值。 第一个和最后一个位置永远不会做出贡献，因为它们只有一个邻居。 

我们必须计算总分（所有局部最大值处的值之和）不超过 k 的排列。 

关键的难点在于排列结构和局部最大值结构都是全局的。 改变一个元素会影响它的邻居是否成为峰值，所以我们不能独立地对待位置。 

约束条件 n ≤ 400 和 k ≤ 400 是决定性的。 排列上的状态空间是 n!，它太大了。 即使 O(n^3) 或 O(n^2 k) 也可能是可接受的，但 n 中的任何阶乘或指数都是不可能的。 这立即表明了一种动态规划公式，我们逐步构建排列并仅跟踪与峰值及其贡献相关的聚合属性。 

“失望”的定义产生了一个微妙的边缘情况。 仅当峰值严格大于两个相邻峰值时，该峰值才有效。 对于较小的 n，尤其是 n = 3，单个局部最大值已经可以消耗 k 的大部分，因此转换必须仔细控制何时形成峰值。 

## 方法

 暴力方法会枚举 1 到 n 的所有排列，通过扫描所有内部位置来计算每个排列的分数，并检查其是否在预算范围内。 这是正确的，但它的运行时间为 O(n!·n)，即使 n = 12 也是不可行的。 

关键的观察是，元素的值仅在其成为局部最大值时才重要，并且局部最大值纯粹由与其邻居的相对顺序决定。 我们可以从左到右构建它们，并只保留足够的信息来决定新完成的三元组是否形成峰值，而不是跟踪完整的排列。 

这表明我们在 DP 中逐一插入元素，并跟踪放置了多少元素、存在多少仍可以形成峰值的“活动边界结构”以及峰值的累积和。 由于 k ≤ 400，我们可以安全地将 DP 限制在总分之上。 

解决此类问题的标准技巧是将排列解释为维护序列的过程，其中每个新插入仅在闭合局部模式时才能创建峰值。 我们根据放置的元素数量和当前的“形状边界”对状态进行建模，通过存在多少个潜在峰值位置隐式编码。 转变对应于以创建新峰值或避免创建新峰值的方式插入新值。 

我们将排列结构简化为基于前缀和受控峰值形成的 DP，确保我们只跟踪插入新元素是否会创建局部最大值及其贡献是什么。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!·n) | O(n!·n) | O(n) | 太慢了|
 | 最佳DP | O(n^2k) | O(n^2k) | O(n·k) | 已接受 |

 ## 算法演练

 我们从最小值到最大值逐步构建排列。

1. 将 dp[i][j] 定义为使用前 i 个插入元素构造有效部分排列的方法数，以使总失望分数恰好为 j。 
2. 我们坚持这样的想法：当插入新元素 x 时，它可以以不会创建新的局部最大值的方式放置，或者如果它位于两个小于 x 的现有元素之间，则它可以成为峰值。 
3. 当我们插入 x 时，我们在概念上在当前大小为 i − 1 的序列中选择一个位置。有 i 个可能的插入点。 只有在两个现有元素之间插入才能创建新的内部峰值； 不能在末端插入。 
4.对于每个插入位置，我们确定是否形成新峰。 如果形成峰值，则其贡献为 x，因此我们将 x 添加到得分维度 j 中。 
5. 我们将 dp[i − 1][j] 转换为 dp[i][j] 以进行安全插入，将 dp[i][j + x] 转换为峰形成插入，并根据导致每种情况的有效插入位置的数量进行加权。 
6. 我们小心地确保更新 dp 时不超过 k，因为任何 j > k 的状态都可以被丢弃。 
7. 处理完从 1 到 n 的所有 i 后，我们对所有 j ≤ k 的 dp[n][j] 求和。 

### 为什么它有效

 关键的不变量是，在处理 i 个元素之后，dp 准确地编码大小为 i 的部分排列的数量，这些排列仅按其累积的峰值分数分组，而与它们的内部排序细节无关。 这是有效的，因为新元素是否成为局部最大值仅取决于插入时其直接邻居，而不取决于更深的历史记录。 i 个元素的每个排列都可以由恰好 i 个插入历史来构造，并且每个历史都由 DP 转换一致地计数，确保不会出现过多计数或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, K = map(int, input().split())
    
    dp = [[0] * (K + 1) for _ in range(n + 1)]
    dp[0][0] = 1

    for x in range(1, n + 1):
        ndp = [[0] * (K + 1) for _ in range(n + 1)]
        
        for i in range(x):  # current size i before inserting x
            for cost in range(K + 1):
                val = dp[i][cost]
                if not val:
                    continue

                # insert x without creating a peak
                # there are i+1 insertion positions, but only i-1 internal ones can create peaks
                # ends are always safe
                if i + 1 <= n:
                    ways_safe = 2 if i >= 1 else 1
                    ndp[i + 1][cost] = (ndp[i + 1][cost] + val * ways_safe) % MOD

                # insert x as a peak (only if there is an internal position)
                if i >= 2:
                    ways_peak = max(0, i - 1)
                    nc = cost + x
                    if nc <= K:
                        ndp[i + 1][nc] = (ndp[i + 1][nc] + val * ways_peak) % MOD

        dp = ndp

    ans = sum(dp[n][j] for j in range(K + 1)) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```该代码在插入元素的数量和当前的失望成本上实现了二维 DP。 每次迭代都会添加一个新值 x 并将所有先前的状态向前转换。 

“安全插入”情况考虑了不会立即形成局部最大值的位置。 乘以此类位置的数量反映出我们正在通过插入历史而不是显式序列来计算排列。 

“峰值插入”情况考虑了 x 成为严格局部最大值的位置。 它的成本贡献恰好是x，因此我们相应地增加预算维度。 

直到 K 的所有成本的最终总和给出了所有有效的排列。 

一个微妙的实现点是 dp 是通过当前大小 i 而不是固定排列位置重新索引的。 这避免了需要显式维护完整序列，同时仍然通过插入位置保留正确的组合计数。

 ## 边缘情况

 对于 n = 3，任何排列都只有一个内部元素，除非它是中心的最大元素，否则它会成为峰值。 DP 正确地处理了这个问题，因为仅当插入的元素超过两个相邻元素时才对峰形成进行计数，并且在小尺寸下，不存在可以创建多个竞争峰的内部插入位置。 

当 k = 0 时，算法限制出现任何峰值的所有状态。 这迫使所有转换仅进入那些没有内部元素成为局部最大值的配置，有效地仅计算单调插入结构。 DP 通过放弃任何使成本增加到超过零的转换来自然地处理这个问题。
