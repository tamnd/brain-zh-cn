 ## 解决方案
 ## 问题理解

 我们给定一个长度的字符串$n$。 唯一允许的操作是选择一个索引$i$并交换位置处的字符$i$和$i+k$。 该操作可以重复任意多次。 

因此，字符串通过沿着连接位置的边交换而演变$i$有位置$i+k$。 问题不在于找到一个最终配置，而是计算在任意次数的此类交换之后可以从原始字符串到达​​多少个不同的字符串。 

关键的观点是停止思考“操作”，而是思考指数之间的连通性。 每个交换仅排列索引图的连接组件内的字符$1 \dots n$，边连接的地方$i$和$i+k$。 在每个连接的组件内，字符可以任意重新排列，因为相邻的交换会在该组件上生成完整的对称组。 

约束条件允许$n$最多$10^6$，因此任何显式构建排列或枚举可达字符串的方法都是不可能的。 我们需要对索引图进行线性或近线性分解。 

一个天真的想法是模拟交换并尝试使用 BFS 探索所有可到达的字符串。 这会立即失败，因为即使是单个大小的组件$m$可以生成$m!$即使对于排列，存储或遍历它们也是不可行的$m = 10$。 

第二个天真的想法是独立处理每个连接的组件并乘以组件大小的阶乘。 这更接近正确，但它错过了一个关键细节：字符并不不同，因此仅排列相同字母的组件内的排列不会创建新字符串。 

破坏粗心方法的边缘情况包括：

 如果$n = 4, k = 2, s = "aabb"$, 索引分为多个部分$\{1,3\}$和$\{2,4\}$。 每个组件都有两个字符，因此每个组件贡献一个因子$2$, 给予$4$。 一个简单的每分量阶乘方法将给出$2! \cdot 2! = 4$，与此处匹配，但这是偶然的，因为重复很简单。 

如果$n = 4, k = 1, s = "abca"$，整个字符串是一个组成部分，因此可达字符串都是多重集的排列。 答案是$4! / (2!)$。 任何忽略重复字母的方法都会输出$24$，这是错误的。 

真正的困难是结合图结构（由步骤引起的组件）$k$），每个组件内都有多重排列。 

## 方法

 互换定义了一个图表，其中每个位置$i$连接到$i+k$当有效时。 该图是依赖于的链的集合$k$。 如果我们重复应用该操作，我们可以沿着这些边移动，因此每个连接的组件都是所有指数全等模$k$，但前提是仔细检查步骤如何交互。 

暴力方法将模拟交换并尝试枚举所有可达的排列。 每次交换仅更改本地顺序，但重复应用程序会探索组件内的所有排列。 在最坏的情况下，一个组件可以包含$\Theta(n)$指数，因此枚举增长为$O((n!) )$，这是不可能的。 

关键的见解是由边引起的图$i \leftrightarrow i+k$将索引精确划分为$g = \gcd(n, k)$独立组件。 在每个组件内，位置按以下步骤循环连接$k$，形成相等结构的不相交循环。 每个组件都是独立的，因此最终答案是该组件内不同字符排列数量的组件的乘积。 

对于具有字符数的组件$c_1, c_2, \dots$，不同重排的数量为：$$\frac{m!}{\prod c_i!}$$在哪里$m$是元件尺寸。 完整的答案是所有组件的乘积。 

我们预先计算阶乘和逆阶乘模$10^9+7$并按残基类模对索引进行分组$g$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力枚举|$O(n!)$|$O(n!)$| 太慢了|
 | 组件 + 多重计数 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 计算$g = \gcd(n, k)$。 这决定了索引在重复交换下如何分裂成独立的循环。 原因是反复加减$k$保留余数模$g$，因此没有任何操作会跨越这些边界。 
2. 初始化阶乘和逆阶乘数组至$n$。 这些是有效计算多项系数所必需的，因为每个分量都需要除以重复字符的阶乘。 
3. 将索引划分为$g$组，其中组$r$包含索引$r, r+g, r+2g, \dots$。 这是有效的，因为这些正是由大小重复跳跃引起的连接组件$k$。 
4. 对于每组，收集出现在这些位置的字符。 我们正在有效地提取一个在组内完全可置换的多重集。 
5. 计算组中每个字符的频率并计算不同排列的数量：$m! / \prod c_i!$。 这反映出交换操作可以实现组件内部的任意排列，但相同的字母不会创建新的字符串。 
6. 将所有组的结果乘以模$10^9+7$。 

### 为什么它有效

 交换图分解为通过重复添加定义的连接组件$k$，并且每个组件都独立于其他组件。 在组件内部，相邻交换生成所有排列，因此可达集恰好是其多组字符的所有排列。 由于组件不相互作用，因此总计数是独立多项计数的乘积。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def build_fact(n):
    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)

    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    return fact, invfact

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    g = 0
    import math
    g = math.gcd(n, k)

    fact, invfact = build_fact(n)

    visited = [False] * n
    ans = 1

    for start in range(g):
        if visited[start]:
            continue

        freq = {}
        idxs = []
        i = start

        while not visited[i]:
            visited[i] = True
            idxs.append(i)
            i = (i + k) % n

        for i in idxs:
            freq[s[i]] = freq.get(s[i], 0) + 1

        m = len(idxs)
        ways = fact[m]
        for c in freq.values():
            ways = ways * invfact[c] % MOD

        ans = ans * ways % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```阶乘预处理构建了用于所有组件的组合引擎。 gcd 确定存在多少个独立循环。 使用重复加法遍历每个循环$k$模数$n$，它正确遵循交换连接。 

访问过的数组确保每个索引只处理一次。 在每个组件内，我们计算字符重数并应用多项式公式。 最终的乘法结合了独立的分量。 

一个微妙的点是步行时使用模运算$i = (i + k) \% n$。 这正确地模拟了循环结构； 每个起始索引在$0 \dots g-1$生成没有重叠的完整轨道。

 ## 边缘情况

 当出现一种边缘情况时$k = n$。 在这种情况下，不存在有效的交换，因为$i+k$对所有人来说都是超出范围的$i$，所以字符串是固定的。 该算法处理这个问题是因为$g = \gcd(n,n) = n$，但每个分量的大小为 1，产生答案 1。 

另一种情况是所有字符都相同。 尽管每个组件在结构上允许多种排列，但多项系数会崩溃为每个组件 1。 该算法正确返回 1，因为所有阶乘除法都取消。 

最后一个微妙的情况是$k$与 互质$n$。 然后$g=1$整个字符串是一个组成部分。 该算法将整个字符串简化为单个多项式系数，这与交换将所有内容连接到一个完全可置换系统的事实相匹配。
