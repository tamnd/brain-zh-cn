 ## 解决方案
 ## 问题理解

 我们正在使用一个有向图，其节点代表主题，其边代表它们之间的单向关系。 该图从一大组现有边开始，这些边形成有向非循环结构，然后我们得到一系列逐条插入的附加边。 

对于来自节点的每个新有向边$u$到一个节点$v$，我们必须决定添加这条边是否会创建一个涉及两者的有向循环$u$和$v$。 如果出现这样的循环，我们输出“YES”，否则输出“NO”。 回答后，该边将永久添加到图表中并影响所有未来的查询。 

约束条件是$N \le 1000$是中心结构线索。 尽管最多可以有$5 \cdot 10^5$初始边，节点数量较少表明维持密集的可达性信息是可行的。 查询数量$Q \le 1000$也很小，这强烈表明我们可以承受比对数或线性边缘更昂贵的每个查询图更新。 

一个关键的观察是新边缘引入的循环$u \to v$仅取决于是否已经存在一条路径$v$回到$u$在当前图表中。 如果存在这样的路径，则添加$u \to v$闭合一个有向循环。 如果没有，则不会。 

当节点之间存在多个间接路径时，就会出现一种幼稚但重要的边缘情况。 例如，如果$v \to a \to b \to u$存在，然后添加$u \to v$即使没有直接边也会创建一个循环$v \to u$。 除非考虑完全可达性，否则纯粹基于邻接的检查或本地检查在这里会失败。 

另一个微妙的情况是更新改变了未来查询的可达性。 例如，即使当前查询没有创建循环，它也可能会引入影响后续查询的新可达性，因此我们必须在每次插入后更新传递结构。 

## 方法

 暴力破解的想法很简单：对于每个查询边$u \to v$，我们运行图搜索（DFS 或 BFS）$v$看看我们能否到达$u$。 如果可以的话，添加边就会形成一个循环； 否则它不会。 之后，我们将边插入到邻接表中。 

这是正确的，因为有向循环包含$u$和$v$恰好存在于$v$已经可以达到$u$。 然而，这种方法变得昂贵，因为每次可达性检查都需要花费$O(N + M)$，并且自从$M$长大到大约$5 \cdot 10^5 + 1000$，总成本$Q = 1000$在 Python 中，查询变得临界或更糟，特别是由于重复遍历大型邻接表。 

关键的见解是$N$非常小。 我们可以维护一个动态传递闭包矩阵，而不是每次都从头开始重新计算可达性。 具体来说，我们维护一个布尔矩阵`reach[i][j]`指示是否有一条路径从$i$到$j$。 

当新的边缘$u \to v$添加后，可以创建新的路径形式$x \to u \to v \to y$。 这表明传递更新：如果$x$可以达到$u$， 然后$x$现在可以到达所有可到达的节点$v$，类似地，所有可以到达的节点$u$现在可以访问$v$的传出可达性。 这本质上是一个本地化的传递闭包更新，并且因为$N \le 1000$，类似 Floyd 的增量更新对于每个查询都是可行的。 

我们维持：

 -`reach[i][j] = True`如果$i$可以达到$j$- 可选地，反向可达性是通过更新中的转置结构隐式实现的

 对于每个边缘插入，我们只需要通过现在可以通过以下方式连接的节点来传播改进：$u \to v$。 这是在$O(N^2)$每个查询。 

自从$Q \le 1000$和$N \le 1000$，最坏情况的复杂度约为$10^9$布尔运算，当使用本地引用仔细实现并避免沉重的 Python 开销时，这在优化的 Python 中是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个查询的强力 DFS |$O(Q(N+M))$|$O(N+M)$| 太慢了|
 | 增量传递闭包 |$O(QN^2)$|$O(N^2)$| 已接受 |

 ## 算法演练

 我们维护所有节点的可达性矩阵。 

### 步骤

 1.初始化一个2D布尔矩阵`reach`尺寸的$N \times N$，如果需要，将除自可达性之外的所有条目设置为 false。 

然后我们读取所有初始边并标记`reach[u][v] = True`。 这些边形成一个 DAG，因此最初不存在循环，但由于有多条边，可达性已经很重要。 
2. 使用 Floyd-Warshall 式松弛计算初始传递闭包。 

对于每个中间节点$k$， 如果$i \to k$和$k \to j$，然后设置$i \to j$。 

这在处理查询之前提供了正确的基线可达性结构。 
3. 对于每个查询边$u \to v$,首先检查是否`reach[v][u]`是真的。 

如果是，那么已经有一条路径$v$回到$u$，所以添加$u \to v$关闭涉及两个节点的有向循环。 输出“是”。 
4. 如果`reach[v][u]`为假，输出“NO”，因为此时无法形成涉及两个端点的循环。 
5. 无论答案如何，插入新边并更新可达性。 

我们通过考虑每个可以到达的节点来传播新的可达性$u$现在可以到达所有可以到达的地方$v$，并且类似地$v$继承所有可以到达的节点的可达性$u$。 

这是通过迭代所有对来完成的$(i, j)$并通过新启用的连接进行更新。 

### 为什么它有效

 在任何时刻，`reach[i][j]`正确表示当前图中是否存在有向路径。 新优势的唯一途径$u \to v$可以创建一个涉及两个端点的循环，如果已经存在一条来自$v$到$u$。 这个条件正是我们测试的。 

更新步骤保留了正确性，因为每个新引入的路径必须至少经过新边一次。 任何这样的路径都会分解为以以下结尾的前缀$u$, 边缘$u \to v$，以及从以下位置开始的后缀$v$。 从两侧传播可达性可确保捕获所有此类组合，从而在每次插入后保持完全的传递闭合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    n0 = n

    reach = [[False] * n for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        reach[u-1][v-1] = True

    # Floyd-Warshall transitive closure
    for k in range(n):
        rk = reach[k]
        for i in range(n):
            if reach[i][k]:
                ri = reach[i]
                for j in range(n):
                    if rk[j]:
                        ri[j] = True

    for _ in range(q):
        u, v = map(int, input().split())
        u -= 1
        v -= 1

        if reach[v][u]:
            print("YES")
        else:
            print("NO")

        if not reach[u][v]:
            # add edge and update closure
            # copy lists for speed
            ru = reach[u]
            rv = reach[v]

            # nodes that can reach u
            for i in range(n):
                if reach[i][u]:
                    ri = reach[i]
                    # everything reachable from v becomes reachable from i
                    for j in range(n):
                        if rv[j]:
                            ri[j] = True

            # nodes reachable from v now inherit from u
            for j in range(n):
                if rv[j]:
                    ru[j] = True
```该解决方案是围绕紧凑的布尔邻接矩阵构建的。 初始 Floyd-Warshall 传递确保在查询开始之前建立所有间接可达性，因此每个查询都可以依赖一致的全局视图。 

在更新期间，第一个传播循环扩展了所有前辈的可达性$u$通过$v$的传出结构。 第二个循环扩展了可达性$u$直接地。 这两个方向一起模拟必须经过插入边的所有新路径。 

一个微妙的实现细节是避免不必要的写入：我们仅在以下情况下传播`reach[i][u]`或者`rv[j]`是正确的，这显着减少了常数因子。 此外，索引始终保持从 0 开始，以避免循环内重复转换。

 ## 边缘情况

 关键的边缘情况是当图表已包含长间接路径但查询端点之间没有直接连接时。 例如，一条链$1 \to 2 \to 3 \to 4$。 查询$4 \to 1$必须返回“YES”，因为$1$达到$4$间接地，所以$4$可以回到$1$插入后。 该算法处理这个问题是因为`reach[1][4]`关闭后已经为真，因此反向检查可以正确检测循环形成。 

另一种情况是重复强化可达性。 如果有一条边$u \to v$添加时$u$已经达到$v$，不应应用任何更新。 条件`if not reach[u][v]`确保我们避免冗余传播，在保持正确性的同时保持最少的更新。 

最后一个微妙的情况是通过多步骤更新创建独立的循环。 即使两个端点最初都没有到达另一个端点，中间更新也可能会引入一条路径$v \to u$在查询之前，使稍后的插入立即循环。 因为我们总是检查`reach[v][u]`在查询时使用完全更新的闭包，这种依赖关系自然会得到处理。
