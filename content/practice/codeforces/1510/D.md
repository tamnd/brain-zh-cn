 ## 解决方案
 ## 问题理解

 我们有`n`牌。 每张卡片包含一个正整数。 我们可以选择卡片的任何非空子集并将所有选定的数字相乘。 

目标不仅仅是获得最后一位小数位等于的乘积`d`。 在所有这样的子集中，我们希望产品值尽可能大的子集。 

第一个观察结果是，只有乘积的最后一位数字对约束很重要。 如果数字以数字结尾`x`，乘以它会改变当前的最后一位数字`r`进入`(r * x) mod 10`。 

第二个观察结果是，实际产品可能会变得非常大。 和`n = 100000`，甚至存储候选产品也是不可能的。 我们需要另一种方式来比较产品。 

界限`a_i ≤ 1000`非常有帮助。 每个数字仅贡献十个可能的最后数字之一。 因此最后一位数字的状态空间仅为 10。另一方面，`n`非常大，因此任何依赖于子集大小或乘积大小的解决方案都被排除。 我们需要大致线性的时间。 

当所需的数字可以通过乘积差异很大的几个子集来实​​现时，就会出现微妙的边缘情况。 

例子：```
3 6
2 3 8
```两个都`{8}`和`{2,3}`产生最后一位数字`8`和`6`分别。 仅基于最后一位数字的贪婪策略会忽略产品规模很重要的事实。 

另一个棘手的情况涉及数字`1`。```
3 4
1 4 11
```乘以`1`不会改变最后一位数字，但它可能仍然属于最优子集。 任何重建过程都必须允许这些元素出现。 

当不存在有效子集时，会出现最后的边缘情况。```
2 1
2 4
```每个产品都是偶数，所以最后一位数字永远不可能是`1`。 正确的输出是`-1`。 

## 方法

 暴力解决方案检查每个子集，计算其乘积，检查最后一位数字，并保留最大的有效乘积。 

这是正确的，因为它明确地评估了每种可能性。 不幸的是有`2^n`子集。 为了`n = 100000`这是完全不可行的。 

关键的观察结果是约束仅取决于乘积的最后一位数字。 模 10 后只有 10 个可能的余数。 

假设我们知道子集乘积的最后一位数字。 要比较最后一位数字相同的两个子集，我们只需要知道哪个乘积更大。 自从`log(ab) = log(a) + log(b)`,

 最大化乘积相当于最大化对数和。 

这将问题转化为只有十个状态的动态规划问题。 

让`dp[r]`是所有已处理子集的最大可能对数和，其乘积以数字结尾`r`。 

当我们处理一个新号码时`a`，其最后一位数字是`x`，我们可以开始一个仅包含`a`，或附加`a`到任何先前已知的子集。 结果最后一位数字变为`(r * x) mod 10`。 

由于只有十个残基，因此每个元素仅执行恒定量的工作。 整个DP以线性时间运行。 

为了输出实际的子集，每当状态改善时我们都会存储父信息。 DP 完成后，我们通过向后跟踪父指针来重建所选索引。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(1) | O(1) | 太慢了|
 | DP 最后一位数字 | O(10n) | O(10n) | O(10n) | O(10n) | 已接受 |

 ## 算法演练

 1.让`w_i = log(a_i)`。 
2. 维护`dp[10]`， 在哪里`dp[r]`存储其乘积以数字结尾的已处理子集的最大对数值`r`。 
3. 将每个状态初始化为负无穷大。 
4. 一一处理数字。 
5. 对于当前号码`a`， 让`x = a mod 10`。 
6. 创建当前 DP 的副本，因为转换必须仅使用上一次迭代中的状态。 
7. 考虑仅包含以下内容的子集`a`。 会产生残渣`x`和价值`log(a)`。 
8. 对于每一个残留物`r`已经存在的，通过附加创建一个新的子集`a`。 新的残渣变成`(r * x) mod 10`，新值变为`dp[r] + log(a)`。 
9. 每当转换改善状态时，记录足够的信息以便稍后重建解决方案。 存储之前的残差和之前的索引。 
10. 所有号码处理完后，检查残留物`d`。 
11.如有残留`d`无法访问，打印`-1`。 
12.否则通过从最终状态向后跟随父指针来重建子集。 
13.输出对应的数字。 

### 为什么它有效

 对于每一个残留物`r`，DP存储所有以残差结尾的子集中最大的对数值`r`处理完数组的前缀后。 

单例转换保证每个子集都可以从其第一个选择的元素开始。 扩展转换保证每个较大的子集都可以由较小的子集加上一个新元素形成。 

由于对数严格递增，对数和较大的子集总是具有较大的乘积。 因此，DP 准确地保留了每个残基类别的具有最大乘积的子集。 

通过对处理后的元素进行归纳，考虑每个可达子集，并且对于每个残基，保留最好的一个。 因此残差的状态`d`处理后所有数字对应于最后一位数字等于的最大可能乘积`d`。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

NEG = -1e100

n, d = map(int, input().split())
a = list(map(int, input().split()))

dp = [NEG] * 10

take = [[False] * 10 for _ in range(n)]
prev_digit = [[-1] * 10 for _ in range(n)]
prev_index = [[-1] * 10 for _ in range(n)]

for i, val in enumerate(a):
    x = val % 10
    w = math.log(val)

    ndp = dp[:]

    if w > ndp[x]:
        ndp[x] = w
        take[i][x] = True
        prev_digit[i][x] = -1
        prev_index[i][x] = -1

    for r in range(10):
        if dp[r] <= NEG / 2:
            continue

        nr = (r * x) % 10
        cand = dp[r] + w

        if cand > ndp[nr]:
            ndp[nr] = cand
            take[i][nr] = True
            prev_digit[i][nr] = r
            prev_index[i][nr] = i - 1

    dp = ndp

if dp[d] <= NEG / 2:
    print(-1)
    sys.exit()

res = []
cur_digit = d
idx = n - 1

while idx >= 0:
    if take[idx][cur_digit]:
        res.append(a[idx])
        pd = prev_digit[idx][cur_digit]
        pi = prev_index[idx][cur_digit]

        cur_digit = pd
        idx = pi
    else:
        idx -= 1

print(len(res))
print(*res)
```DP 数组仅存储每个残基的最佳对数值。 重建表会记住哪个转换创建了状态。 

比较使用对数而不是乘积。 这可以避免使用大整数，同时保留顺序。 

重建结构是最微妙的部分。 每当状态改善时，我们都会准确记录之前的残留物产生的状态。 未改进的状态必须保留其旧含义，这就是从复制的 DP 数组执行转换的原因。

 ## 边缘情况

 当所有数字都是偶数并且目标数字是奇数时，任何乘法序列都不能产生奇数的最终数字。 DP 根本无法到达相应的残留物并正确打印`-1`。 

当多个子集产生相同的最后一位数字时，DP 会比较对数和而不是子集大小。 例如：```
3 6
2 3 16
```子集`{2,3}`产生`6`， 尽管`{16}`产生`16`。 余数相同，但对数值`16`较大，因此 DP 保留第二子集。 

当数组包含多个时，例如```
4 4
1 1 1 4
```加一时余数不变，但对数值也不变。 任一选择都是有效的，因为两者生产相同的产品。 DP仍然重建正确的最优子集。
