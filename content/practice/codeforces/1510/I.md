 ## 解决方案
 ## 问题理解

 在此问题中，您将扮演参与者 Izzy，进行一系列投注，预测即兴比赛是否会被评级。 对于每次投注，您都会看到所有其他参与者的预测，然后做出您自己的预测。 之后，真正的结果就会揭晓。 您的目标不一定是始终预测正确，而是确保在所有投注后您的错误总数不会明显高于表现最好的参与者。 具体来说，如果错误最少的参与者$b$错误，你的错误不得超过$1.3 \cdot b + 100$。 

输入由其他参与者的数量组成$n$以及投注的数量$m$。 对于每个赌注，您都会读取一个长度的字符串$n$显示其他参与者的猜测，输出单个字符 0 或 1 作为您的预测，然后读取实际结果。 最多有 1000 名参与者和 10,000 个赌注，但每个赌注都可以独立处理，因为预测不会相互影响。 

关键的挑战是$b$，最佳参与者的基准是未知的，实际结果可能是对抗性的。 因为评分是宽容的 - 您可以承受乘法 1.3 因子和加法 100 - 您不需要完美的准确性。 一个简单的解决方案可能只是随机猜测，但您可以利用参与者的预测来做出稍微更明智的猜测。 

边缘情况包括所有参与者预测相同值或预测均等的投注。 总是猜测 0 或总是复制参与者的天真方法仍然可以在评分公式下发挥作用，但您需要避免无效输出并确保交互式法官的正确刷新。 

## 方法

 暴力策略会尝试学习或跟踪其他参与者的猜测和结果的模式。 对于每个赌注，您可以比较所有以前的赌注，找到最常见的模式，并根据历史准确性进行猜测。 虽然这可能会提高准确性，但在交互式环境中却不必要地复杂且存在风险。 跟踪 1000 名参与者的 10,000 次投注的所有结果需要大量内存，并且会带来延迟，但它在概念上是正确的，因为它使用信息来最大限度地减少错误。 

关键的一点是，得分允许有很大的优势。 你不需要完美的预测。 其他参与者的预测提供了一个提示：如果投票 1 的参与者多于投 0 票的参与者，那么如果参与者倾向于准确，那么比赛投票 1 的可能性会稍大一些。 一个简单的启发式方法是为每次投注选择参与者中的多数预测。 该策略速度极快，需要最少的内存，并且性能良好，足以保持在$1.3 \cdot b + 100$实践中的错误。 在对抗性情况下，确定性规则（例如始终预测 0）也会通过，但多数启发式往往会进一步减少错误。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力追踪历史准确性 | O(n*m) | O(n*m) | 矫枉过正，不必要|
 | 多数投票启发式 | O(n*m) | O(1) | O(1) | 接受且简单|
 | 总是预测 0 | O(米) | O(1) | O(1) | 已接受，基线 |

 ## 算法演练

 1. 读取整数$n$和$m$参加人数和赌注。 
2. 对每个赌注重复以下操作：

 1.读取长度的字符串$n$包含参与者的预测。 
2. 统计该字符串中1的个数。 
3. 如果1的个数大于等于一半$n$，预测 Izzy 为 1。 否则，预测 0。这实现了简单的多数投票启发式。 
4. 打印预测并刷新输出以确保法官收到它。 
5. 阅读实际结果以进行下一个投注。 您不需要存储结果。 
3. 继续，直到全部$m$投注已处理。 

为什么有效：每次投注都是独立的，并且评分允许乘法和加法容差。 使用多数投票启发法可以将 Izzy 的预测与其他参与者更有可能的选择结合起来，从而减少错误。 即使启发式错误，慷慨的评分也能确保 Izzy 保持在允许的错误范围内。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import math

n, m = map(int, input().split())

for _ in range(m):
    s = input().strip()
    ones = s.count('1')
    # majority vote heuristic
    if ones * 2 >= n:
        guess = '1'
    else:
        guess = '0'
    print(guess, flush=True)
    actual = input().strip()  # read outcome, no need to store
```该解决方案首先读取问题参数，然后一一处理赌注。 计算 1 的数量可以实现快速多数决策，无需额外存储。 打印后刷新保证了交互的正确性。 必须读取实际结果才能进行下一个投注，但不会影响未来的预测。

 ## 边缘情况

 如果所有参与者投票相同，例如“1111”，则算法预测 1，这与多数一致。 对于均匀分割，例如“1100”，启发式通过预测 1 打破平局，确保确定性行为。 当n=1时，直接遵循单个参与者的投票。 在所有情况下，刷新并读取实际结果可确保正确的交互。 该算法从不打印无效字符，并且每次投注总是准确地产生一个猜测。
