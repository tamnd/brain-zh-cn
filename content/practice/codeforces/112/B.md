 ## 解决方案
 ## 问题理解

 我们有一块大小为的方板`2n × 2n`，分为晶胞。 一个单元格已被标记。 我们想知道是否可以沿着网格线画一条切割路径，使木板旋转后分成两个全等的部分，而切割路径却不会接触到标记的单元格。 

关键细节是旋转后得到的两个部分必须变得相同。 对于边长均匀的正方形，自然旋转对称性以棋盘中间为中心。 

输入给出边长`2n`和坐标`(x, y)`标记的单元格。 行和列都是 1 索引的。 我们必须打印`"YES"`如果存在这样的切割，否则`"NO"`。 

约束很小，边长最多为 100，因此性能不是这里的挑战。 困难在于识别隐藏在陈述中的几何观察。 强力的几何构造是不必要的并且容易出错。 

不明显的部分是了解每个有效的对称切割都不可避免地会出现哪些单元格。 

考虑最小的有趣情况：```
4 2 2
```正方形是`4 × 4`。 中心区域由四个单元组成：```
(2,2) (2,3)
(3,2) (3,3)
```如果标记的单元格是这四个单元格之一，则答案是`"NO"`。 

为什么？ 任何将正方形分成旋转相等的两半的有效切割都必须穿过板的正中心。 在均匀大小的网格中，中心位于这四个单元的交叉点，因此每个可能的对称分割路径都接触该中心`2 × 2`堵塞。 

粗心的解决方案可能只检查确切的中心点，而忘记了均匀大小的网格有四个而不是一个中心单元。 

另一个容易犯的错误是使用从零开始的推理和从一开始的坐标。 对于一个`6 × 6`董事会，中央单元是：```
(3,3) (3,4)
(4,3) (4,4)
```不是`(2,2)`和`(3,3)`。 

例如：```
6 3 4
```必须产生`"NO"`因为`(3,4)`位于中央街区内。 

但：```
6 2 4
```产生`"YES"`因为标记的单元格位于该不可避免的区域之外。 

## 方法

 强力解释将尝试沿着网格边缘明确构造每条可能的切割线，验证它将板分成相等的旋转一致区域，并检查路径是否接触标记的单元格。 

即使对于一个`100 × 100`板，可能的格子路径的数量是巨大的。 搜索空间呈指数增长，因为在每个网格交叉点，路径可能会向多个方向分支。 这种方法几乎立即变得不可行。 

蛮力之所以感觉自然，是因为该语句讨论的是几何切割而不是简单的算术条件。 但这里的几何形状极其严格。 

关键的观察结果是，每个有效分区都必须遵循围绕正方形中心 180 度旋转对称。 如果边长是偶数，则中心位于四个单元格之间。 任何对称的分割路径都必须经过该中心区域。 

这意味着唯一永远无法避免的单元格是四个中间单元格：```
(n,n)
(n,n+1)
(n+1,n)
(n+1,n+1)
```如果标记的单元格是其中之一，则每个有效的切割都与它相交，所以答案是`"NO"`。 

对于每个其他单元格，可以绘制合适的对称切口来避开标记位置，因此答案是`"YES"`。 

整个问题简化为检查是否`(x, y)`属于中央的`2 × 2`堵塞。

 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取边长`2n`和单元格坐标`(x, y)`。 
2. 计算`n = side_length // 2`。 

四个不可避免的中心单元完全由这个值决定。 
3. 检查标记的单元格是否位于中心区域内`2 × 2`堵塞。 

这恰好发生在以下时间：```
x is either n or n+1
and
y is either n or n+1
```4. 如果两个条件都成立，则打印`"NO"`。 

每个对称切割都必须经过该区域。 
5. 否则，打印`"YES"`。 

在中心块之外，存在有效的对称分区，避开标记的单元。 

### 为什么它有效

 有效的切割将正方形分成两部分，旋转后两部分变得相同。 这种对称性迫使分割路径穿过正方形的几何中心。 

由于边长均匀，几何中心位于四个单元格之间。 任何穿过中心的路径都必然触及中心`2 × 2`堵塞。 这四个细胞是不可避免的。 

通过选择适当的对称切割可以避免所有其他单元。 所以答案是`"NO"`正好适合四个中央细胞，并且`"YES"`其他地方。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

side, x, y = map(int, input().split())

n = side // 2

if (x == n or x == n + 1) and (y == n or y == n + 1):
    print("NO")
else:
    print("YES")
```实现直接遵循数学观察。 

首先我们计算`n`，它标识了板的中间。 由于边长始终是偶数，因此中心由四个单元而不是一个单元组成。 

条件：```
(x == n or x == n + 1)
```检查该行是否属于中间的行对。 同样的逻辑也适用于列。 

两个条件必须同时成立，标记的单元格才能位于中心区域内`2 × 2`堵塞。 

一个常见的差一错误是忘记网格使用基于一的索引。 对于一个`4 × 4`板，中心行是`2`和`3`， 不是`1`和`2`。 

该解决方案使用恒定时间和恒定内存。

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    side, x, y = map(int, input().split())

    n = side // 2

    if (x == n or x == n + 1) and (y == n or y == n + 1):
        print("NO")
    else:
        print("YES")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output.strip()

# provided sample
assert run("4 1 1\n") == "YES", "sample 1"

# minimum valid size, central cell
assert run("2 1 1\n") == "NO", "minimum size central cell"

# minimum valid size, another central cell
assert run("2 2 2\n") == "NO", "all cells are central in 2x2"

# outside center block
assert run("6 2 4\n") == "YES", "outside forbidden region"

# exact center boundary
assert run("6 3 4\n") == "NO", "central block detection"

# maximum size edge position
assert run("100 1 100\n") == "YES", "large board edge cell"
```| 测试输入| 预期产出 | 它验证了什么 |

 |`2 1 1`|`NO`| 最小的板，每个单元都是中心 |
 |`2 2 2`|`NO`| 确认所有四个单元格均被禁止`2 × 2`|
 |`6 2 4`|`YES`| 单元格与中心相邻但仍然有效 |

 ## 边缘情况

 考虑尽可能最小的电路板：```
2 1 1
```这里`n = 1`，所以中心块是：```
(1,1) (1,2)
(2,1) (2,2)
```标记的单元属于该块，因此算法打印`"NO"`。 

如果实现假设只有一个中心单元，那么这种情况很容易处理不当。 

现在考虑：```
6 2 3
```我们计算：```
n = 3
```禁止的单元格是：```
(3,3) (3,4)
(4,3) (4,4)
```标记的单元格`(2,3)`位于中心块的正上方，但不在中心块内部。 算法正确打印`"YES"`。 

这可以捕捉到程序员意外地将禁止区域扩展到真实范围之外的错误。`2 × 2`中心。 

最后，考虑：```
100 50 51
```这里：```
n = 50
```中央细胞是：```
(50,50) (50,51)
(51,50) (51,51)
```标记的单元格`(50,51)`位于块内，因此算法打印`"NO"`。 

这验证了逻辑是否可以正确缩放到最大输入大小，而无需任何特殊处理。
