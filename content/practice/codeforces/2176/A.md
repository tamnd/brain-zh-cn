 ## 解决方案
 ## 问题理解

 我们得到一个数字数组，并且允许我们在非常特定的条件下重复删除元素。 每一步选择两个索引$i < j$使得值在$i$严格大于该值$j$，然后删除位置处的元素$j$。 数组缩小，其余元素保持其相对顺序。 

任务是确定如果我们总是选择最佳的对，可以执行多少次这样的删除。 

思考该过程的一种有用方法是，每个操作都会删除一个元素，该元素当时在其左侧某处至少有一个严格更大的元素。 一旦某个元素的左侧没有更大的元素，它就会受到“保护”并且永远无法删除。 

限制很小：$n \le 100$和$t \le 50$。 这立即排除了比以下更复杂的事情$O(n^2)$每个测试用例无需担心。 即使三次方法仍然可能通过，但我们应该瞄准干净的贪婪或线性扫描想法，而不是大量模拟的方法。 

微妙之处在于，删除会改变数组，因此像“计算最初存在多少个反转”这样的天真的推理是不正确的。 已删除的元素可以解锁未来的删除或更改哪些元素可以充当有效元素$i$。 

一个典型的错误是假设每个反转都对应一个可移动元素。 这会失败，因为单个元素只能被删除一次，并且有效左伙伴的可用性取决于不断发展的数组，而不是初始状态。 

例如，在一个递增数组中$[1,2,3]$，最初没有有效的对，并且无法删除任何内容。 在递减数组中，例如$[3,2,1]$，除了第一个元素之外的每个元素最终都可以被删除，但只能以链式方式删除。 

## 方法

 一个蛮力的想法是模拟这个过程。 我们重复扫描所有对$(i, j)$，删除一个有效的$j$，并继续，直到不存在任何移动。 每次扫描费用$O(n^2)$，我们最多可以删除$n$元素，导致$O(n^3)$每个测试用例。 和$n \le 100$，这是临界点，但仍然可以接受。 然而，它模糊了结构并使正确性推理变得更加困难。 

关键的观察是，唯一能够幸存的元素是那些在最终配置中左侧没有严格更大元素的元素。 一旦我们全局地看待这个过程，移除就可以被视为选择一个从左到右严格非递减的子序列，因为任何违规$a_i > a_j$允许删除$a_j$。 

这重新定义了问题：我们实际上正在尝试删除尽可能多的元素，以便剩余的数组没有递减对。 这意味着最终的数组必须是非递减的。 

所以问题就变成了：找到最大的删除次数，这样我们就可以保留一个非减子序列。 同样，最大化删除意味着最小化通过保持元素有序而获得的有效最终非递减序列的大小。 

最小可能的最终数组对应于构造一个贪婪的非递减子序列，该子序列仅保留必要的“记录正确结构的最小值”，但更简单的表征是有效的：最终数组正是在某种进化意义上不受其右侧任何元素“支配”的元素的集合。 这减少了从左到右的贪婪扫描，同时保持左侧保留结构的运行最大值。 

更具体地说，我们模拟哪些元素必须保留：我们保留第一个元素，然后每当我们看到一个严格小于先前保留的元素的元素时，它就是可移除的； 否则它就会成为一个新的“保持峰值”。 这个贪婪结构中保留的峰值数量给出了最小的最终大小，答案是$n - \text{kept}$。 

这是有效的，因为任何成为剩余后缀中新最大值的元素以后都无法删除，而任何不是其左侧最大值的元素始终可以通过该最大值删除。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 从没有保留元素和跟踪迄今为止在保留结构中看到的最大值的变量开始。 
2. 从左到右扫描阵列。 
3. 如果当前元素大于当前保留的最大值，我们必须保留它并更新最大值。 
4. 否则，当前元素最终可以被删除，因为它的左侧存在一个更大的元素可以作为$i$在操作中。 
5. 计算这条规则保留了多少个元素。 
6. 答案是元素总数减去保存的计数。 

第 3 步背后的直觉是，每当我们看到新的全局最大值时，任何较早的元素都无法帮助稍后删除它，因为其左侧不存在更大的元素。 在任何删除序列中，该元素在结构上都变得不可逆。 

### 为什么它有效

 不变的是，保留的元素在演化的最优配置中形成严格递增的“从左到右最大值”序列。 每个非保留元素的左侧至少有一个比它大的保留元素，保证它可以在某个阶段被删除。 相反，每个保留的元素都是新最大值的第一次出现，因此没有有效的操作可以删除它。 

这将数组划分为必须保留的基本最大值和可删除的受控元素，并且没有任何操作可以将受控元素转换为非受控元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        kept = 0
        mx = 0

        for x in a:
            if x > mx:
                kept += 1
                mx = x

        print(n - kept)

if __name__ == "__main__":
    solve()
```实现直接遵循贪心规则。 变量`mx`存储迄今为止保留的元素中的最大值。 每次遇到超过它的值时，我们都会增加基本元素的数量。 

一个微妙的点是相等不会创建新的保留元素。 如果`x == mx`，它总是可移除的，因为只有当严格大于或等于其左侧的最大值元素存在时，它才可以用作删除锚点，并且相等的值永远不会成为必要的“新最大值”。

 ## 边缘情况

 完全递增的数组，例如$[1,2,3,4]$是不正确的反转计数推理的最简单的失败点。 该算法将所有元素保持为最大值，从而导致零删除，这与现实相符，因为不存在有效的对。 

完全递减的数组，例如$[4,3,2,1]$展示最大删除量。 每个新元素都严格小于以前的元素，因此它始终可以移除，直到只剩下第一个元素为止。 

高低交替的形态，例如$[1,5,2,6,3,7]$测试算法是否错误地计算了多次删除。 这里每个高值都会重置最大值，不留下可移动的结构； 贪婪扫描正确保留所有元素，产生零操作。
