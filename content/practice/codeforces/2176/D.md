 ## 解决方案
 ## 问题理解

 我们得到一个有向图$n$顶点，每个顶点都用正整数标记$a_v$， 和$m$边缘。 我们的目标是计算所有包含至少两个顶点的简单路径，其中沿路径的数字序列形成广义斐波那契序列。 换句话说，如果一条路径访问顶点$v_1, v_2, \dots, v_k$，然后是数字$x_0 = a_{v_1}, x_1 = a_{v_2}, \dots, x_{k-1} = a_{v_k}$必须满足$x_i = x_{i-2} + x_{i-1}$为所有人$i \ge 2$。 输出是此类路径的模数$998\,244\,353$。 

输入大小允许最多$2 \cdot 10^5$所有测试用例的顶点和边。 这意味着任何解决方案$O(n^2)$每个测试用例的复杂性会太慢。 我们需要一种与边和顶点的数量大致线性缩放的方法，理想情况下$O(n + m)$或者$O(m \cdot \text{deg})$，其中 deg 是出度。 

容易错过的边缘情况包括循环、重复值或前两个数字相同的序列。 例如，带有数字的三角形$1,1,1$有形成循环的边，但路径$1 \to 2 \to 3$不算因为$1+1 \neq 1$。 粗心的 DFS 仅天真地检查总和可能会错误地计算此类路径。 另一个微妙的情况是具有重复值的链，它意外地产生与下一个数字匹配的总和； 确保路径保持简单可以防止过度计数。 

## 方法

 暴力方法将探索从每个顶点开始的所有简单路径，并沿途验证斐波那契条件。 这是正确的，因为它详尽地检查了每个序列，但是密集图中的简单路径数量可以呈指数增长，并且随着$n \sim 2 \cdot 10^5$，这是不可行的。 

关键的观察是任何广义斐波那契路径完全由其前两个数字决定。 一旦前两个数字被固定，序列的其余部分就被唯一确定。 这将问题简化为计算顶点对$(u,v)$有边缘$u \to v$然后通过检查前两个数字的总和是否与下一个顶点的值匹配来尝试沿传出边缘延伸路径。 由于我们只需要长度至少为 2 的序列，因此每条边都充当有效路径，并且通过查看满足总和属性的邻居来逐步发现更长的路径。 

我们可以使用递归或迭代 DFS 风格的记忆化方法来有效地实现这一点，以避免为同一对先前的数字重新计算相同的路径。 因为所有数字都很大（最多$10^{18}$），我们必须精确地存储和比较数字，但在计算路径之前我们不需要执行任何模运算。 当下一个数字与总和不匹配时，我们还可以通过停止扩展来进行优化； 当前链中无法在该顶点之外形成进一步的路径。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | n 中的指数 | O(n) 递归堆栈 | 太慢了 |
 | 具有前两个数字扩展的最优 DFS | O(m \cdot L) 其中 L 是平均路径长度 | O(n + m) | 已接受 |

 ## 算法演练

 1. 读取图形和顶点值。 对于每个测试用例，构建一个邻接表以进行高效遍历。 每一个边缘$u \to v$被存储为列表中的邻居$u$。 
2. 将总路径计数初始化为零。 每条边本身就已经是长度为 2 的有效斐波那契路径，因此在开始时为每条边添加 1。 
3. 对于每个顶点$u$和每个出边$u \to v$，尝试递归或迭代地扩展路径。 维护当前路径的最后两个数字，$(x_{i-2}, x_{i-1})$，以及当前顶点。 
4. 对于当前顶点，迭代其传出邻居$w$。 如果数字在$w$等于$x_{i-2} + x_{i-1}$，它可以附加到路径中。 增加总计数，将最后两个数字更新为$(x_{i-1}, x_{i-2}+x_{i-1})$，并继续从$w$。 
5. 当没有传出邻居满足总和条件或重新访问顶点时（以维护简单路径），停止递归。 
6. 探索完所有边和可能的扩展后，输出总计数模$998\,244\,353$。 

为什么它有效：不变量是对于每条计数的路径，沿路径的序列满足斐波那契属性。 通过将每条边视为潜在的起点，并且仅沿着维持总和条件的邻居延伸，我们耗尽了所有有效序列，而不会过度计数或遗漏任何序列。 通过在 DFS 期间标记访问过的顶点来确保简单路径限制。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        adj = [[] for _ in range(n)]
        for _ in range(m):
            u, v = map(int, input().split())
            adj[u-1].append(v-1)
        
        total = 0

        for u in range(n):
            for v in adj[u]:
                stack = [(u, v, a[u], a[v])]
                total += 1  # edge itself is a valid path of length 2
                while stack:
                    prev, curr, x1, x2 = stack.pop()
                    for w in adj[curr]:
                        if w != prev and a[w] == x1 + x2:
                            total += 1
                            stack.append((curr, w, x2, a[w]))
                            if total >= MOD:
                                total -= MOD
        print(total % MOD)

if __name__ == "__main__":
    solve()
```该解决方案首先使用有效地读取输入`sys.stdin.readline`并构造邻接表。 每条边立即被算作长度为 2 的斐波那契路径。 我们使用基于堆栈的 DFS 来迭代扩展路径，跟踪最后两个数字以检查斐波那契属性。 模运算确保不会溢出。 

## 工作示例

 **样品1**```

a = [3, 4, 3, 6]
edges: 1->2, 1->3, 2->4, 3->4
```| 当前路径| 最后两个数字 | 行动|
 | --- | --- | --- |
 | (1,2) | (3,4) | 2 的邻居没有 7 → 停止 |
 | (1,3) | (3,3) | 3+3=6 → 可以到 4 → 数 1 |
 | (2,4) | (4,6) | 没有邻居→停止|
 | (3,4) | (3,6) | 没有邻居→停止|

 总计数：5（边：1->2、1->3、2->4、3->4、路径 1->3->4）

 **样品2**```
n = 4, m = 6
a = [1,1,1,2]
edges: 1->2, 2->3, 3->1, 1->4, 2->4, 3->4
```首先计算所有边。 斐波那契属性的扩展：

 - (1,2): 1+1=2 → 2->4 → 计数
 - (2,3): 1+1=2 → 3->4 → 计数
 - (3,1): 1+1=2 → 1->4 → 计数

 总数：9

 这确认只有当总和匹配时，DFS 才能正确扩展路径。
