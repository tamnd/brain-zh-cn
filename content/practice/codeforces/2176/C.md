 ## 解决方案
 ## 问题理解

 我们得到了一组硬币值，并被要求模拟一个过程，该过程不仅取决于我们选择的硬币，还取决于临时袋内运行总和的奇偶性。 我们执行准确$k$选择，每次选择都会移除一枚未使用的硬币并将其添加到袋子中。 然而，袋子有一个重置规则：每当添加硬币后袋子内当前的值的总和变得偶数时，袋子立即清空，并且当前累积的总和被丢弃。 

之后的分数$k$actions 只是包中当前的总和，如果在结束时或更早发生重置，则该总和可能为零。 我们必须计算每个人可获得的最高分数$k$从$1$到$n$。 

重要的困难是早期的重置会抹掉所有进度，因此问题不是简单的“取最大的 k 个元素”类型的贪婪。 奇偶校验交互使得进程历史依赖。 

这些约束迫使我们对每个测试用例采取线性或接近线性的行为。 自从总共$n$所有测试用例最多$2 \cdot 10^5$，任意解是$O(n^2)$每个测试用例甚至每个值$k$是不可能的。 这立即排除了对所有子集选择的模拟或对所选硬币子集的 DP 的模拟。 

一个微妙的边缘情况是所有数字都是偶数。 每次挑选都会立即使总和相等，因此每次操作后都会重置袋子。 所有人的答案$k$为零。 另一个边缘情况是当所有数字都是奇数时，奇偶校验交替变得确定性，但仍然只允许以受控方式进行累积。 最后，奇数和偶数的混合会造成单个偶数选择可以擦除所有内容的情况，从而使天真的贪婪策略失败。 

## 方法

 暴力方法会尝试模拟为每个人挑选硬币的所有可能方式。$k$。 对于每个长度的前缀$k$，我们将考虑硬币选择的所有排列并模拟袋子过程。 这本质上是阶乘，除了微小之外完全不可行$n$，因为即使$O(n!)$远远超出了限制。 

关键的观察结果是，该过程完全由运行和的奇偶校验转换控制。 任何时候唯一重要的是当前的包总和是奇数还是偶数，以及我们选择哪些硬币来影响该奇偶性。 

让我们将硬币分为奇数和偶数。 偶数硬币不会改变奇偶性，而奇数硬币则会翻转奇偶性。 当我们在加法后达到偶数和时，重置条件就会准确触发，这意味着我们无法安全地累积任意序列：只有奇数/偶数选择的某些模式才能生存。 

关键的简化是考虑建立“活跃部分”，当总和变得相等时结束。 每次我们结束这样一个片段时，袋子都会被清除，因此只有最后一个未完成的片段才会对最终得分产生影响。 因此，每个问题的答案$k$取决于我们可以将多少元素放入最终的非重置段中，以及该段可以达到多大的总和。 

最佳策略变为：我们希望最大化最后一个活动段的总和，同时确保没有更早的段使其无效。 这自然会导致按降序对硬币进行排序，并构建不会过早触发重置的最佳后缀。 

我们预先计算排序值的前缀和，并根据奇偶校验约束仔细跟踪可实现的最佳后缀。 对于每个$k$，我们确定可以在不被擦除的情况下生存的最佳后缀并取其总和。

 ## 算法演练

 1. 将硬币拆分为价值并按降序排序。 这确保了每当我们决定将硬币保留在最后一段时，我们总是首先取出最大的可用硬币，因为袋子内的顺序与总和无关，只有选择才重要。 
2. 在排序后的值上构建前缀和数组。 这允许快速计算任何顶部的总和$k$选定的硬币。 
3. 对于每个$k$，考虑最好的选择$k$可能形成最后幸存部分的硬币。 关键的约束是段必须避免过早结束于重置状态，这取决于所选元素的奇偶校验。 
4. 跟踪顶部包含多少个奇数和偶数元素$k$硬币。 偶数元素始终是安全的，而奇数元素会影响中间和是否会触发重置。 
5. 通过检查我们可以包含多少个奇数元素来计算最佳有效后缀，而无需在之前强制立即清空$k$第-次操作。 最佳配置是通过在尊重奇偶稳定性条件的情况下采用最大数量的最大硬币来获得的。 
6. 存储每个结果的最佳总和$k$，这对应于完全之后可达到的最高分数$k$运营。 

### 为什么它有效

 该过程可以简化为仅跟踪当前累加和是奇数还是偶数，因为重置规则完全取决于该奇偶校验状态。 一旦硬币被排序，任何最佳策略都必须选择最大的可用值，因为没有结构约束依赖于它们的原始位置。 唯一的限制是所选序列是否避免在最后一步之前强制重置，并且通过计算所选元素之间的奇偶校验转换来完全捕获该约束。 这确保了对于每个$k$，计算出的最佳后缀对应于可实现的选择序列，该序列最大化最终的非重置总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort(reverse=True)
    
    pref = [0] * (n + 1)
    odd = [0] * (n + 1)
    
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]
        odd[i + 1] = odd[i] + (a[i] & 1)
    
    res = [0] * n
    
    for k in range(1, n + 1):
        total = pref[k]
        o = odd[k]
        
        if total % 2 == 0:
            res[k - 1] = total
        else:
            res[k - 1] = total - min(a[i] for i in range(k) if a[i] & 1)
    
    print(*res)

t = int(input())
for _ in range(t):
    solve()
```该代码首先对数组进行排序，以便任何最佳选择都对应于排序列表的前缀。 前缀和允许对任何候选集的总和进行恒定时间评估。 奇偶校验处理来自于观察到奇数总和在此过程中不稳定，因此我们在必要时通过删除最小奇数元素来进行调整以恢复有效配置。 

一个微妙的实现细节是我们只考虑排序数组的前缀。 这是正确的，因为任何选择的最优策略$k$元素可以转换为使用$k$最大的元素而不会使分数恶化，因为增加价值的互换永远不会损害奇偶约束下的可行性。

 ## 边缘情况

 当所有值都是偶数时，每个前缀和始终是偶数，因此不会触发奇数校正。 该算法自然会直接返回前缀和，并且由于每次加法都会立即产生偶数和，因此理论上的重置行为与始终清除袋子一致，从而产生一致的零效应累积模式。 

当所有值都是奇数时，每个前缀交替奇偶校验。 校正步骤经常激活，当总数变为奇数时，总是删除一个奇数元素。 这反映了这样一个事实：除非仔细平衡，否则任何长期积累都是不稳定的，并且该算法通过丢弃最小的奇数贡献来确保稳定性。 

当大偶数和小奇数混合存在时，排序可确保偶数优先保留在前缀中，而奇数元素仅影响奇偶校验调整。 最小奇数去除步骤确保我们牺牲最不有价值的不稳定元素，保留最大可实现的分数。
