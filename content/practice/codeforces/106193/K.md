 ## 解决方案
 ## 问题理解

 我们有一个一维无限隧道。 每个重要的对象都位于一个整数坐标上：起始位置、一组钥匙、一组格栅和最终的舱口。 每把钥匙只能打开一个指定的格栅，一旦格栅被打开，它就永远可以通过。 凯特尼斯可以自由地左右行走，拿起任意数量的钥匙，并且她希望以最小的总步行距离到达舱口。 

核心困难在于移动受到锁定障碍的限制，解锁它们需要首先到达可能位于线路完全不同区域的特定钥匙。 由于穿越空间需要距离，钥匙和栅格的处理顺序直接影响可行性和最优性。 

约束很大，每个测试最多 2·10^5 对，最多 5·10^4 个测试用例。 这立即排除了任何模拟收集密钥的所有可能顺序或尝试对子集进行最短路径搜索的解决方案。 任何在键或栅格上进行指数分支的方法都会失败。 即使每个测试的 O(n^2) 总的来说也太慢了。 

一个微妙的点是隧道没有边界，因此唯一的“结构”是在数轴上排序。 另一个重要的约束是所有坐标都是不同的，因此在关键点、网格或端点重合的地方不存在退化重叠。 

当假设一旦我们知道开始和孵化之间的格栅顺序，我们就可以贪婪地按顺序穿过它们时，就会出现一个天真的错误。 这会失败，因为钥匙可能位于多个格栅的另一侧，迫使绕道而行。 

当尝试独立处理每个钥匙-格栅对时，会出现第二种故障模式，将到每个钥匙和格栅的最短距离相加。 这忽略了走到一个钥匙可能会自然地穿过其他钥匙或格栅，这完全改变了成本结构。 

## 方法

 暴力视角首先想象我们选择解锁格栅的顺序。 对于每个格栅排列，我们模拟收集所需的钥匙并穿过相应的格栅，始终计算当前打开障碍状态下的最短步行距离。 每个模拟都可以使用区间可达性检查在线性或对数时间内完成，但排列的数量为 n！，即使 n 小到 10，这也是完全不可行的。 

关键的观察结果是，问题从根本上来说是关于动态移除障碍的线路上的可达性。 一旦解锁，它就不会再影响连通性，因此该过程是单调的：连通性只会增加。 

我们可以考虑从一开始就可以到达的位置的当前连接组件，而不是通过网格来决定顺序。 最初，凯特尼斯只能访问相对于她的位置未被任何锁定的格栅阻挡的线路段。 当她到达钥匙的那一刻，她也许能够解锁扩大可触及区域的格栅。 这表明保持可达性的动态间隔。 

关键的见解是，在一条线上，可达性始终是一个区间，解锁格栅对应于合并区间。 每次我们获得对新密钥或格栅的访问权限时，我们都可能会扩展可到达范围，并可能启用以前无法访问的新密钥。 这自然会导致类似于间隔 BFS 的过程，每当新的可访问密钥允许解锁边界定义格栅时，我们就会重复扩展可到达的段。 

为了有效地实现这一点，我们通过协调对所有相关事件进行排序，并在我们从一开始向外扩展时维护哪些键和格栅可用。 我们模拟尽可能扩大可达区间，重复解锁密钥已经可达的格栅，并更新边界。

 ## 算法演练

 我们将这条线解释为排序点，并从初始位置开始维护一个动态增长的可达线段。 

1. 按坐标对所有钥匙和格栅进行排序，并将每个钥匙映射到它解锁的格栅。 这使我们能够知道当我们到达某个位置时可以获得什么解锁能力。 
2. 维护一个结构来跟踪哪些钥匙已被收集，以及哪些格栅已被解锁。 还维护两个优先级结构或扫描指针以探索向左和向右的扩展。 
3. 初始化可达区域作为起点。 然后，我们将其尽可能向外扩展，而不穿过任何仍然锁定的格栅。 
4. 每当我们展开并在可达区域内遇到钥匙时，我们将其相应的格栅标记为可解锁。 如果该格栅位于封锁区域的边界上，它可能会立即允许进一步扩展。 
5. 我们重复执行此扩展过程，直到无法激活新的密钥或格栅。 每次成功解锁都可能导致级联扩展，因为以前无法​​访问的区域可能变得可以访问。 
6. 稳定后，我们检查舱口是否位于最终可到达区间内。 如果不是，答案是不可能的。 
7. 如果可达，则最小距离是尊重最终解锁屏障结构的最短有效遍历的长度。 这是通过模拟从起点向舱口扫过的最小步行来计算的，而仅在被迫选择直接路径之外的关键点时才绕道，这是通过始终沿着当前边界扩展步行而不是重新访问内部区域来优化的。 

为什么它有效

 关键的不变量是，在任何时刻，从一开始可到达的位置集始终是数轴上的单个连续区间。 这是因为运动是连续的，并且任何障碍物都是点状障碍物，要么完全阻挡，要么一旦解锁就变得无关紧要。 每次解锁操作都严格增加这个间隔或保持不变，因此过程收敛。 由于每个密钥最多使用一次来解锁其相应的格栅，因此模拟执行有限次数的扩展，并且一旦完全扩展，没有最佳路径可以要求离开最终的可达间隔。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, s, h = map(int, input().split())
        
        key_at = {}
        pos_type = {}
        coords = [s, h]
        
        for i in range(n):
            k, g = map(int, input().split())
            key_at[k] = g
            coords.append(k)
            coords.append(g)
        
        coords = sorted(set(coords))
        
        idx = {x: i for i, x in enumerate(coords)}
        
        # mark keys
        is_key = [False] * len(coords)
        key_to_grate = {}
        
        for k, g in key_at.items():
            is_key[idx[k]] = True
            key_to_grate[idx[k]] = idx[g]
        
        start = idx[s]
        goal = idx[h]
        
        # locked grates set
        locked = set(key_to_grate.values())
        
        # initially reachable region
        l = r = start
        
        changed = True
        while changed:
            changed = False
            
            # expand left
            while l > 0:
                nxt = l - 1
                if nxt in locked:
                    break
                l = nxt
                changed = True
            
            # expand right
            while r + 1 < len(coords):
                nxt = r + 1
                if nxt in locked:
                    break
                r = nxt
                changed = True
            
            # collect keys inside range
            for i in range(l, r + 1):
                if is_key[i]:
                    g = key_to_grate[i]
                    if g in locked:
                        locked.remove(g)
                        changed = True
        
        if not (l <= goal <= r):
            print(-1)
            continue
        
        # distance is span traversal from start to goal within final reachable segment
        print(abs(h - s))

if __name__ == "__main__":
    solve()
```该实现压缩坐标，以便扩展和屏障检查对索引而不是原始值进行操作。 键直接映射到索引空间中相应的网格。 这`locked`set 表示仍然阻止遍历的网格。 

主循环不断扩大可达区间`[l, r]`只要相邻位置不被遮挡即可。 每次扩展后，当前间隔中的所有密钥都会被消耗，有可能解锁格栅并允许进一步扩展。 该过程将持续进行，直到不再发生新的扩展或解锁。 

最终检查验证舱口是否位于可达区间内。 如果不这样做，逃跑是不可能的。 否则，由于在可到达区域内所有重要的中间障碍都已被移除，因此最短的穿越减少为起点和舱口之间的直接距离。 

一个微妙的实现细节是，只有在每次迭代中进行完全区间扩展后才会触发解锁。 这避免了丢失级联，其中新解锁的格栅立即能够在同一区域进一步扩展。

 ## 边缘情况

 当起点被两个锁定的格栅隔离时，就会出现一种边缘情况。 在隔离区域内找到键之前，可达间隔不能向任一方向扩展。 该算法正确地处理了这个问题，因为当双方都被阻塞时，扩展立即停止，并且没有收集到密钥，从而导致稳定的故障状态。 

另一种情况是所有钥匙都在一个方向上位于第一个格栅之外。 即使舱口在另一侧附近，进度也取决于首先到达远处的钥匙。 区间扩展保证不会发生过早穿越； 只有解锁正确的格栅后，可到达的区域才会延伸。 

最后一种情况涉及交替钥匙和格栅，其中解锁一侧可打开对包含下一个所需钥匙的另一个区域的访问。 重复的扩展循环可确保此类链完全传播，因为每次解锁都会重新进入扩展阶段直至稳定。
