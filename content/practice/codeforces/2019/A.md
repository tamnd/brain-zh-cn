 ## 解决方案
 ## 问题理解

 我们得到一个正整数数组，并要求选择一个元素子集来着色为红色，但有一个简单的限制：两个红色元素不能相邻。 一旦我们选择了红色元素，分数就被定义为两个量的总和：红色元素中的最大值和所选红色元素的总数。 我们的目标是最大化这个分数。 

输入由多个测试用例组成。 每个测试用例都有一个整数`n`指定数组的大小，后跟数组元素本身。 我们必须输出每个测试用例的最高分数。 因为数组大小`n`最多可以达到 100 个，每个元素最多可以达到 1000 个，我们知道，只有当我们能够修剪或简化可能性时，对红色元素的所有子集进行强力检查才是可行的。 

非明显的边缘情况包括最大元素位于边界的数组、具有所有相同元素的数组或选择每个其他元素是最佳的数组。 例如，如果数组是`[5, 1, 5]`，将第一个和最后一个元素着色为红色，得分为`5 + 2 = 7`。 如果一种简单的方法只是选择全局最大的元素，并为每个不相邻的选择添加一个元素，那么它可能会错过以产生更高总分的模式选择多个较小元素的机会。 

## 方法

 暴力方法很简单：迭代数组的每个可能的子集，检查子集是否遵守非邻接约束，计算分数并取最大值。 这是可行的，因为数组很小，但子集的数量是`2^n`，大约可达`1.27 × 10^30`为了`n = 100`，远远超出了可行的范围。 即使进行修剪，这也太慢了。 

关键的观察结果是，禁止相邻红色元素的约束和评分函数具有简单的交互作用：最大元素的贡献与我们选择的其他元素的数量无关，并且额外的红色元素总是将每个元素的分数精确地增加 1。 因此，最佳策略是最大化红色元素的数量，因为我们总是可以包含其中最大的元素。 这将问题简化为一个更简单的问题：找到非邻接约束下可以选择的最大元素数，即上限`n / 2`。 一旦我们知道了最大的元素和我们可以选择的元素的数量，最大分数就是`max(array) + ceil(n/2)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，请阅读`n`和数组`a`。 
3. 确定数组中最大的元素。 这总是对分数有贡献，因为选择最大的元素永远不会比忽略它更糟糕。 
4. 计算在邻接约束下我们可以选择的红色元素的最大数量。 对于长度的线性数组`n`， 这是`(n + 1) // 2`。 原因是我们总是可以从第一个或第二个开始选择所有其他元素，以在不违反邻接限制的情况下最大化计数。 
5. 最大分数是最大元素与上一步计算的红色元素数量之和。 
6. 打印每个测试用例的结果。 

为什么它有效：关键的不变量是任何红色元素通过计数将分数精确地添加 1，并且最大红色元素独立贡献。 在尊重邻接性的同时选择尽可能多的元素可以保证我们不会错过增加计数的机会。 因为我们总是包含全局最大元素，总和`max_element + count`是最大的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    max_elem = max(a)
    count = (n + 1) // 2
    print(max_elem + count)
```该解决方案首先读取测试用例的数量。 对于每个测试用例，它读取数组大小和数组本身。 这`max()`函数快速找到最大的元素。`(n + 1) // 2`计算我们可以在非相邻模式中选择的最大元素数，同时考虑偶数和奇数`n`。 最后，将这些相加即可得到最高分。 我们使用整数除法来避免浮点问题，这至关重要，因为数组大小是小整数。

 ## 边缘情况

 对于长度为 1 的数组，例如`[100]`，算法正确计算`max_elem = 100`和`count = (1 + 1)//2 = 1`，得分为 101。对于长度为 2 且元素相同的数组`[1, 1]`，算法计算`max_elem = 1`和`count = (2 + 1)//2 = 1`，所以分数是`2`。 对于具有交替大小元素的数组，该算法始终包含最大元素，并且对每个其他元素进行计数可确保遵守非邻接规则。 这涵盖了所有不明显的边缘场景，证明了正确性。
