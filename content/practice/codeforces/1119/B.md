 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 冰箱有高度`h`正好有两列。 搁板可以插入任意高度，这意味着我们可以自由地将冰箱划分为任意高度的水平隔间。 每个瓶子占一列并有高度`a[i]`。 

任务不是选择瓶子的任何子集。 我们必须按顺序考虑瓶子并找到最大的`k`这样瓶子`1..k`可以同时放入冰箱内。 

关键的观察结果是，由架子创建的每个隔间的宽度为 2。最多两个瓶子可以占据相同的垂直高度，因为冰箱只有两列。 如果两个瓶子共用一个隔间，则隔间的高度必须至少是两个瓶子中较高的一个。 由于架子可以放置在任何地方，因此只有所需的高度才重要。 

瓶数最多为`1000`。 这足够小，即使是`O(n² log n)`解决方案是完全可以接受的。 冰箱的高度可以大到`10^9`，但高度值仅用于算术比较，因此大界限不会造成任何困难。 

一个常见的错误是将所有瓶子的高度相加。 例如：```
3 7
2 3 5
```答案是`3`， 虽然`2 + 3 + 5 = 10 > 7`。 

原因是瓶子可以并排放置。 配对高度`(5,3)`仅使用`5`垂直空间单位和瓶子`2`使用另一个`2`，总共`7`。 

另一个容易犯的错误是任意配对瓶子，而不是最佳配对。```
4 8
1 4 4 4
```排序后我们得到`[1,4,4,4]`。 

配对`(1,4)`和`(4,4)`需要`4 + 4 = 8`，这很合适。 

不小心的安排，例如`(1)`+`(4)`+`(4,4)`需要`1 + 4 + 4 = 9`，这不适合。 

可行性检查必须始终使用最佳的配对策略。 

当瓶子数量为奇数时，会出现第三种微妙的情况。```
3 6
1 2 4
```排序后的高度为`[1,2,4]`。 

最佳布置仅使用最大的瓶子，并将其余两个配对。 所需高度为`4 + 1 = 5`， 不是`4 + 2 = 6`。 错误地处理奇数通常会产生错误的答案。 

## 方法

 暴力解决方案会尝试每一个`k`从`1`到`n`并判断是否有瓶子`1..k`合身。 为了检查可行性，我们可以将所有可能的瓶子配对枚举到两列隔间中，并计算所需的最小高度。 这显然是正确的，因为它检查了每一种排列，但配对的数量呈指数增长并且变得完全不切实际。 

冰箱的结构提供了更强有力的观察。 由于每个层的宽度为 2，因此每个隔间贡献了放置在其中的瓶子中的最大高度。 为了最大限度地减少总使用高度，我们应该在必要时将最高的瓶子放在单独的隔间中，并将较小的瓶子与它们配对。 

假设我们想测试第一个是否`k`瓶子适合。 测量他们的身高并对他们进行排序。 

对于偶数个瓶子：```
b0 ≤ b1 ≤ b2 ≤ b3 ≤ ... ≤ b(k-1)
```最佳排列方式是从顶部将相邻的瓶子配对：```
(b(k-2), b(k-1))
(b(k-4), b(k-3))
...
```所需高度变为：```
b(k-1) + b(k-3) + ...
```对于奇数个瓶子，最小的瓶子单独占据一个隔间，其余瓶子类似地配对。 所需的高度再次通过对排序数组末尾的每隔两个元素求和来获得。 

这提供了有效的可行性测试。 

如果第一个`k`瓶子适合，那么任何较小的前缀也适合，因为移除瓶子不会使放置变得更困难。 这种单调性允许二分搜索`k`。

 ## 方法

 可行性条件是单调的。 如果瓶子`1..k`适合，然后瓶子`1..(k-1)`也适合。 

这立即表明对答案进行二分搜索。 

对于候选人`k`，我们提取第一个`k`高度，对它们进行排序，并计算所需的最小冰箱高度。 

排序后，最佳策略是将瓶子配对，使每对中最大的瓶子占总瓶子数。 无论搭配什么，最大的瓶子都必须贡献其全部高度。 第二大贡献者应该尽可能小，这是通过将大瓶子配对在一起来实现的。 

因此，所需的高度只是位置元素的总和：```
last, last-2, last-4, ...
```在已排序的数组中。 

如果这个金额不超过`h`，前缀是可行的。

 ## 算法演练

 1.二分查找答案`k`在范围内`[1, n]`。 
2. 对于候选值`k`，取第一个`k`瓶子高度。 
3. 按非降序对这些高度进行排序。 
4. 从最大的元素开始，每次向左移动两个位置，并将这些高度添加到运行总和中。 
5. 该总和等于这些冰箱所需的最小高度`k`瓶子。 
6. 如果总和最多为`h`， 标记`k`如果可行，继续向右搜索。 
7. 否则向左搜索。 
8. 二分查找时找到的最大可行值就是答案。 

### 为什么它有效

 排序后，每个隔间贡献其最高瓶子的高度。 为了最大限度地减少总贡献，最大的瓶子应该配对在一起。 那么隔间高度的集合就变成了位置处的元素`last, last-2, last-4, ...`。 

任何其他配对都会迫使一些较大的瓶子成为额外隔间的最大值，并且无法减少所需的总高度。 因此，可行性测试计算所选前缀所需的真实最小高度。 

因为可行性对于`k`，二分查找正确找到最大的有效前缀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can_fit(k, a, h):
    b = sorted(a[:k])

    need = 0
    i = k - 1

    while i >= 0:
        need += b[i]
        i -= 2

    return need <= h

def solve():
    n, h = map(int, input().split())
    a = list(map(int, input().split()))

    lo, hi = 1, n
    ans = 1

    while lo <= hi:
        mid = (lo + hi) // 2

        if can_fit(mid, a, h):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```辅助函数执行可行性检查。 它对第一个进行排序`k`装瓶并通过对从末尾开始的每隔一个元素求和来计算所需的最小高度。 

二分查找保持了所有可行答案都位于第一个不可行值左侧的不变性。 当候选人工作时，我们会记录下来并搜索更大的前缀。 当失败时，我们在较小的前缀中搜索。 

一个常见的实现错误是显式地对相邻对求和。 这可行，但引入了额外的索引逻辑。 对位置处的元素求和`k-1, k-3, k-5, ...`直接更简单，并且与隔间高度完全对应。 

另一个微妙的点是`ans`可以安全地开始`1`。 该声明保证至少有一个瓶子总是适合，因为每个瓶子的高度最多为`h`。

 ## 边缘情况

 ### 奇数瓶

 输入：```
3 6
1 2 4
```排序后的前缀：```
[1, 2, 4]
```该算法对位置求和`2`和`0`，给予：```
4 + 1 = 5
```自从`5 ≤ 6`，三个瓶子都适合。 不正确的实现可能会导致`4 + 2 = 6`通过不正确的配对，它在这里仍然有效，但在类似的输入上失败。 

### 精确的身高匹配

 输入：```
4 8
1 4 4 4
```排序：```
[1, 4, 4, 4]
```所需高度：```
4 + 4 = 8
```该算法接受相等，因为条件是`need <= h`。 使用严格的不等式会错误地拒绝这种情况。 

### 许多高瓶

 输入：```
5 5
5 5 5 5 5
```为了`k = 2`:```
need = 5
```可行的。 

为了`k = 3`:```
need = 5 + 5 = 10
```不可行。 

二分查找正确返回`2`。 这种情况验证了单调属性成立并且搜索停止在最大可行前缀处。 

### 小瓶配大瓶

 输入：```
4 7
1 1 1 7
```排序：```
[1, 1, 1, 7]
```所需高度：```
7 + 1 = 8
```答案不是自动的`4`只是因为三瓶很小。 最高的瓶子占据了它的隔间，算法通过对从末尾开始的每隔一个元素求和来捕获这一点。
