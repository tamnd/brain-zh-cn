 ## 解决方案
 ## 问题理解

 我们得到了一种小型语言，其中每个有效单词都由两个不同的小写英文字母组成。 由于字母表是固定的且很小，因此可以通过选择一对有序的不同字母来生成每个可能的单词，例如`ab`,`ac`,`ba`， 等等。 

这些单词按字典顺序排序：首先按第一个字符排序，对于共享相同第一个字符的单词，按第二个字符排序。 换句话说，这是所有有效双字母字符串的字典顺序，但两个字符必须不同。 

对于每个查询词，我们需要确定它在全局排序中的位置。 

关键限制是字典最多包含 26 × 25 = 650 个单词。 这立即告诉我们，任何方法，即使是显式构造整个列表的方法，都足够快。 然而，我们的目标是认识到我们根本不需要建造任何东西。 

经常出现的一个天真的错误是忘记了配对就像`aa`,`bb`等不是有效的单词，并且在按字典顺序推理时意外地计算了它们。 例如，如果我们处理所有对`(i, j)`和`i ≤ j`，我们会错误地包含无效条目并移动所有索引。 

另一个微妙的优势是逐一索引。 由于字典位置从 1 开始，但字符算术本质上是从零开始的，因此粗心的索引会导致一致的移位。 例如，错误地计算了前面有多少个单词`ba`是一个常见的故障点：人们可能会错误地包括`az`然后继续从`ba`没有正确考虑排除的自对。 

## 方法

 一种简单的方法是生成所有有效的两个字母字符串，对它们进行排序，然后线性扫描目标单词。 由于只有 650 种可能性，这已经很高效了。 构建和排序的成本在实践中是恒定的，但从概念上讲，它是 O(26² log 26²)，并且每个查询需要对最多 650 个条目进行线性扫描。 对于多达 650 个测试用例，这仍然可以正常工作。 

然而，这忽略了排序的结构。 字典不是任意的，它是一个完美的字典网格，其中每个第一个字母定义了 25 个单词的块（除了它本身之外的所有第二个字母）。 一旦我们认识到这个结构，我们就可以直接计算答案。 

对于给定的单词`s = xy`，我们想要计算它之前有多少个有效单词。 所有以字母严格小于开头的单词`x`先来吧。 对于每个这样的起始字母，正好有 25 个有效的第二个字母，因此每个字母都贡献固定的块大小。 

之后，在以`x`，我们计算有多少个有效的第二个字母严格小于`y`，排除第二个等于第一的情况。 这成为字母表上的简单索引调整。 

蛮力之所以有效，是因为空间很小，但作为一般策略，它是失败的。 观察到每个第一个字母贡献一个大小为 25 的统一块，从而将问题简化为每个测试用例的恒定时间算术。

 ## 算法演练

 1. 将单词的两个字符转换为从零开始的索引`a`和`b`， 在哪里`'a' → 0`,`'b' → 1`, ...,`'z' → 25`。 这允许对字母表进行算术推理。 
2. 计算有多少个有效单词来自严格小于的所有首字母`a`。 每个这样的第一个字母都贡献 25 个单词，因为它可以与除自身之外的所有字母配对。 所以这有助于`a × 25`。 
3. 在以以下开头的单词块内`a`，计算有多少个有效的第二个字母严格小于`b`。 这通常是`b`，但我们必须减去 1，如果`b > a`因为这对`(a, a)`无效，否则会错误地转移计数。 
4. 加 1 将从零开始的计数转换为从一开始的字典索引。 

### 为什么它有效

 字典可以被视为 26 个连续的块，每个第一个字母一个。 每个块在结构上都是相同的，只是删除了一个无效的第二个字母。 因为这个缺失的条目始终是对角线对`(x, x)`，它只影响自己块内的相对位置，而不会改变较早块的大小。 这种不变性确保了对整个块进行计数然后进行本地校正会产生准确的全局索引。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        a = ord(s[0]) - ord('a')
        b = ord(s[1]) - ord('a')

        # words before block a
        ans = a * 25

        # position inside block a
        if b > a:
            ans += b
        else:
            ans += b - 1

        print(ans + 1)

if __name__ == "__main__":
    solve()
```代码的第一部分计算当前第一个字符之前存在多少个完整的单词块。 由于每个字母恰好贡献 25 个有效单词，因此乘以字母表索引`a`by 25 给出了所有前面单词的完整计数。 

第二部分处理当前块内的本地排序。 通常，第二个字符索引将直接贡献`b`位置，但无效对`(a, a)`位于该序列内，必须跳过。 这就是为什么只有当第二个字符位于字母表中第一个字符之后时我们才减一。 

最后，我们添加 1 以从从零开始的计数转变为所需的从一开始的字典索引。

 ## 边缘情况

 主要边缘行为围绕着缺失的对角线对`(x, x)`。 例如，考虑`ba`。 这里`b = 1`和`a = 0`。 如果没有修正，我们会计算`b = 0`第二个字母的位置，但这错误地假设`bb`存在或那个`ba`出现得晚于应有的时间。 调整`b - 1`确保每个块中所有无效的自对都被跳过一次。 

为了`ac`， 在哪里`a = 0`和`c = 2`，第二个字符大于第一个字符，因此减法不适用。 该索引与纯粹的词典顺序保持一致。 

为了`zx`，我们依赖于它之前存在 25 个完整块的事实，贡献`25 × 25 = 625`字。 在最后一个区块内，`x`排除自身和所有较小的有效字母，从而产生正确的最终位置，而不需要任何特殊的大小写。 

在所有情况下，该算法从不显式构造字典，但它通过将统一的块结构与单个局部校正相结合来保留精确的顺序。
