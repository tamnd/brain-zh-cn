 ## 解决方案
 ## 问题理解

 给定一个正整数，我们想要找到不小于它的最小整数，使其数字之和能被 4 整除。任务不是优化数字本身的算术属性，而是纯粹向上调整数字，直到满足数字和条件。 

输入范围非常小，值最大为 1000。这立即改变了我们对解决方案的看法。 任何从输入开始顺序尝试数字的方法都已经足够快了，因为即使在最坏的情况下，我们也只检查几千个候选者，这在 1 秒的限制下可以忽略不计。 

关键边缘行为来自这样一个事实：稍微改变一个数字就会显着改变它的数字和。 “附近的数字表现平稳”的天真假设在这里并不可靠。 例如，399 的数字和为 21，而 400 的数字和为 4，因此单个增量可以极大地改变属性。 这意味着我们无法得出直接的公式，增量检查是最安全的方法。 

另一个微妙的边缘情况是当起始数字已经满足条件时。 在这种情况下，答案就是数字本身，因此算法不得跳过检查相等性。 

## 方法

 蛮力的想法很简单。 从给定的数字开始，反复检查其数字之和是否能被4整除。如果不能，则增加数字并重试。 由于每次增量都会更改候选值，并且最大值仅为 1000，因此循环最多运行几千次迭代。 

每次检查都会在 O(log n) 时间内计算一个数字总和，这在实践中是恒定的，因为数字最多有 4 位数字长。 即使我们悲观地假设 1000 次迭代，总的工作量也是微不足道的。 

没有任何有意义的结构允许直接跳转到下一个有效数字而不检查中间数字。 当增加数字时，数字和条件不会以单调或可预测的方式演变，因此跳过值可能会丢失最近的有效候选值。 

关键的观察结果很简单，状态空间很小，因此穷举搜索是最佳的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(1000 × 数字) | O(1) | O(1) | 已接受 |
 | 最佳 | O(1000 × 数字) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取整数`a`。 这是我们的起始候选人。 
2. 定义一个辅助函数来计算数字的数字之和。 我们重复使用模 10 提取最后一位数字，并使用整数除以 10 来减少数字。这是有效的，因为十进制表示可以干净地分解为独立的数字贡献。 
3. 使用变量启动循环`n`初始化为`a`。 该变量代表我们正在测试的当前候选者。 
4. 对于每位候选人`n`，计算其数字和。 如果模 4 的数字和等于 0，我们就找到了最小的有效数，因为我们是按升序扫描的。 
5. 如果不满足条件，则递增`n`加 1 并重复检查。 
6. 一旦找到有效数字，立即输出并终止。 

### 为什么它有效

 该算法维护一个简单的不变量：每个小于当前候选值的数字都已被检查并被拒绝为无效。 因为我们严格加 1，所以满足数字和整除条件的第一个数字保证是大于或等于输入的最小可能有效答案。 不会跳过任何候选，因此不会错过任何有效的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def digit_sum(x: int) -> int:
    s = 0
    while x > 0:
        s += x % 10
        x //= 10
    return s

a = int(input().strip())

n = a
while True:
    if digit_sum(n) % 4 == 0:
        print(n)
        break
    n += 1
```该解决方案定义了一个帮助程序来计算数字和，然后从输入向上迭代，直到找到有效的候选者。 该循环保证快速终止，因为在任何 100 个连续数字的块内，必须至少有一个数字和模 4 在此小范围内适当对齐，并且实际上该约束确保几乎立即终止。 

主要的微妙之处是确保为每个候选者重新计算数字和，而不是尝试增量更新它，因为十进制加法中的进位会使本地更新不可靠。

 ## 边缘情况

 一种边缘情况是输入已经有效。 例如，输入 40 的数字和为 4，因此算法首先检查 40，发现它满足条件，然后立即返回而不递增。 这确保了最小调整情况的正确性。 

另一个边缘情况是数字进位转换。 对于输入 999，算法会检查 999（数字和 27），然后检查 1000（数字和 1），然后继续检查，直到达到 1000 或更高（如果需要）。 重要的一点是，没有假设数字和如何跨进位演变，因此无论结构不连续性如何，强力扫描仍然正确。
