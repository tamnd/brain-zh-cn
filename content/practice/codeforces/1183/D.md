 ## 解决方案
 ## 问题理解

 我们得到了几个独立的糖果系列。 每个集合只是整数的多重集，其中每个整数代表一种糖果类型。 我们希望从每个系列中选择一些糖果来制作一件“礼物”。 

限制是我们可以携带每种类型的糖果的数量。 如果我们选择给定类型的某个金额，则该金额在所有选定类型中必须是唯一的。 例如，如果我们拿了 3 颗类型 5 的糖果，那么礼物中不允许其他类型的糖果恰好出现 3 次。 但是，我们可以采用 3 个类型 5、2 个类型 7、1 个类型 9，依此类推，只要所有这些计数都是不同的。 

每个查询的目标是最大化礼物中糖果的总数。 

跨查询的输入大小很大，元素总数最多为 2·10^5。 这立即排除了任何关于频率的二次推理或针对每种类型一一重复调整计数的贪婪模拟。 解决方案必须以大致线性或线性时间处理每个查询。 

当许多类型共享相同的频率时，就会出现微妙的故障情况。 例如，如果我们有频率 [5, 5, 5, 5]，一种简单的方法可能会尝试为所有频率分配值 5，但这违反了唯一性，并且我们必须小心地减少一些计数，同时保留最大总和。 

另一个棘手的情况是频率虽小但数量众多，例如多种类型只出现一次。 将它们全部赋值 1 是无效的，因为计数必须不同，因此只有一种类型可以取 1，另一种类型必须取 0，依此类推。 

这些约束清楚地表明，问题不在于类型的身份，而在于它们的频率以及我们如何将不同的正整数分配给它们的子集以使总和最大化。 

## 方法

 第一个自然的想法是计算每种类型有多少糖果。 假设我们获得频率 f1, f2, ..., fk。 现在我们需要为每个选定的类型分配一个不同的正整数 x，其中 x ≤ fi，并最大化所有选定 x 的总和。 

一个蛮力的想法是尝试所有类型的子集和所有不同值的分配，检查可行性并跟踪最大总和。 即使我们修复了一个子集，分配不同的值也是一个类似排列的问题。 子集的数量为 2^k，并且 k 可能很大，因此即使对于小输入，这也很快变得不可行。 

更结构化的蛮力会从最大频率向下尝试值，贪婪地分配最大的可用不同数字，但重新计算冲突。 当许多频率相似时，这仍然存在 O(k^2) 行为的风险。 

关键的观察是，我们从不关心哪种类型获得哪个计数，只关心我们分配严格递减或至少不同的整数。 为了最大化总和，我们应该首先优先选择较大的分配计数，但我们受到每个频率的限制。 

这将问题转化为：我们有一个容量 fi 的列表，并且我们希望为每个选定的元素分配一个不同的整数 xi ，使得 1 ≤ xi ≤ fi ，从而最大化总和 xi 。 最佳策略是按频率降序排列，并贪婪地分配最大可能的未使用整数，但永远不会超过频率。 

当我们迭代排序的频率时，我们维护下一个可用的整数值。 如果频率小于或等于当前可用值，我们将其限制； 否则我们会减少它以保持清晰度。 

这是有效的，因为任何违反排序贪婪结构的赋值都可以重新排列以增加或保留总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^k·k) | O(2^k·k) | O(k) | 太慢了 |
 | 最优贪心 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们专注于一个查询并将其简化为频率处理。

1. 计算每种糖果类型的出现次数。 

我们构建一个频率数组或字典来存储每种类型的糖果数量。 这会将输入压缩为最多 n 个有意义的值。 
2. 将所有非零频率提取到列表中。 

只有频率才重要； 计数后类型本身就无关紧要了。 
3. 按频率降序排列。 

这确保我们首先分配较大的可用值，从而防止在小分配上浪费容量。 
4. 初始化变量`cur = infinity`（或一个非常大的数字）。 

这代表我们仍然可以分配的最大允许不同计数。 
5. 迭代每个频率`f`按排序顺序。 

我们分配`use = min(f, cur - 1)`因为我们必须保持不同类型的值严格递减。 

如果`use`变为负数或零，我们停止，因为没有保留有效的正不同赋值。 
6. 添加`use`到答案并更新`cur = use`。 

每个步骤都确保我们始终为当前类型选择最大可能的有效不同计数，同时尊重以前的分配。 

### 为什么它有效

 核心不变量是，在处理 i 个频率之后，我们为所选类型分配了严格递减的值，并且在每一步中，我们都不会留下未使用的可行分配。 排序保证我们首先考虑更高容量的类型，而贪婪缩减则确保如果频率太大而无法放入剩余的“槽”，我们会对其进行最小程度的压缩。 任何偏离这一选择的行为要么会违反唯一性，要么会用较小的可行分配替换较大的可行分配，从而减少总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        arr = list(map(int, input().split()))

        freq = {}
        for x in arr:
            freq[x] = freq.get(x, 0) + 1

        vals = sorted(freq.values(), reverse=True)

        cur = n
        ans = 0

        for f in vals:
            if cur <= 0:
                break
            use = min(f, cur)
            ans += use
            cur = use - 1

        print(ans)

if __name__ == "__main__":
    solve()
```该实现首先使用字典将数组压缩为频率。 这是必要的，因为类型本身在计数后就无关紧要了。 

我们按降序对频率进行排序，以便首先分配较大的组，从而最大限度地提高尽早使用大量不同计数的机会。 

变量`cur`跟踪我们可以分配的最大剩余整数。 每次我们分配`use = min(f, cur)`，我们确保不超过可用频率或剩余允许的不同值。 然后我们减少`cur`到`use - 1`以保持严格的唯一性。 

一个常见的实现错误是忘记分配的值必须严格不同。 这完全是通过`cur - 1`。

 ## 边缘情况

 一个关键的边缘情况是许多类型的频率为 1。对于像 [1, 2, 3, 4, 5] 这样的输入，算法将 1 分配给第一种类型，然后必须将 0 分配给所有其他类型。 贪婪归约自然地处理了这个问题，因为 cur 很快下降到 0。 

另一种情况是一种类型占主导地位，例如 [1,1,1,1,1,1]。 第一个作业使用 6，然后是 5，然后是 4，产生一个楼梯，直到耗尽。 这个不变量确保我们永远不会分配相同的计数两次。 

第三种情况是交替中频，例如[3,3,3,2,2]。 排序可确保首先处理较大的组，从而防止早期阻塞较高的可能分配。
