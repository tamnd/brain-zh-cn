 ## 解决方案
 ## 问题理解

 我们得到了几个独立的数据集。 每个数据集中都有多个正整数集，其中每个整数代表问题的“值”。 从这个池中，我们必须选择最多三个值来最大化它们的总和，但有一个严格的限制：不允许任何选定的值除以任何其他选定的值。 

所以如果我们选择数字$x, y, z$，那么这六种有序整除关系都不允许。 即使选择两个数字也已经施加了相同的规则：两个数字都不能整除另一个数字。 目标是找到一个、两个或三个有效数字的最佳总和。 

输入的结构非常重要：最多$2 \cdot 10^5$所有查询的总数，最多$2 \cdot 10^5$查询。 这立即排除了任何尝试每个查询的所有三元组或每个查询重复执行昂贵的因子检查的方法。 任何比每个查询大致线性或近线性更糟糕的事情都会失败，因为总输入大小很大但仍然密集。 

天真的本能是尝试所有三元组，但当值很大并且在查询中重复时，即使对候选者进行双循环也已经太大了。 另一个微妙的陷阱是假设取三个最大的数字总是有效。 这是失败的，因为大数通常与小数有许多可分关系，特别是在像多重链这样的结构化输入中。 

第二种失败模式来自于在不检查整除兼容性的情况下通过递减值进行贪婪选择。 例如，选择较大的数字可能会阻止许多中等大小的候选者，否则这些候选者可以更好地组合成一对或三重。 

## 方法

 暴力方法将枚举大小为 1、2 和 3 的所有子集。对于每个子集，我们检查成对整除性并计算总和，跟踪最大有效结果。 这是正确的，因为它直接遵循约束。 然而，三元组的数量是$O(n^3)$每个查询，这是完全不可行的$n$取决于$2 \cdot 10^5$。 

即使减少到检查所有对然后扩展到第三个元素仍然会导致$O(n^3)$最坏情况下的行为。 瓶颈在于可分性是一个全局结构，而不是局部比较，因此朴素的组合学会反复重新检查相同的关系。 

关键的观察结果是，答案仅取决于每个值的极少数候选者。 如果我们考虑一个数字$x$，所有禁止与它一起出现的数字都是它的约数和倍数。 由于值的边界为$2 \cdot 10^5$，每个数的约数相对较少，并且可以有效地预先计算倍数结构。 

我们预处理频率，然后对于每个候选值计算不可与其整除的值之间存在多少个兼容伙伴。 我们不检查任意三元组，而是只尝试以结构化方式构建解决方案：将最大值作为候选锚点，然后使用预先计算的兼容性过滤尝试最佳兼容的第二个和第三个选择。 

核心思想是，大小最多为三个的最佳集合必须包含在可分性约束下“局部最优”的值，并且我们可以通过迭代值空间而不是元素索引来枚举候选者。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^3)$|$O(1)$| 太慢了 |
 | 带预计算的基于值的枚举 |$O(M \log M)$每个查询（摊销）|$O(M)$| 已接受 |

 这里$M = 2 \cdot 10^5$。 

## 算法演练

 我们在价值空间而不是索引空间中工作。 主要思想是预先计算每个值的频率，然后贪婪但安全地推理选择 1、2 或 3 个值。 

### 步骤

 1. 统计数组中每个值的出现频率。 

我们将输入压缩到频率数组中，以便集中处理重复的值，而不是单独处理。 
2. 预先计算按降序排序的当前值列表。 

这确保我们始终首先考虑高贡献候选人，这一点至关重要，因为答案是一个最大化问题。 
3. 计算每个值$x$，是否有另一个值$y$是兼容的。 

如果两个值都不相除，则两个值是兼容的。 我们没有明确构建完整的兼容性图； 相反，我们利用除数枚举来快速检查关系。 
4.尝试最好的单一值。 

任意值$x$可以单独使用，贡献$x$如果存在的话。 最好的单一选择就是呈现的最大价值。 
5. 尝试最好的一对。 

我们迭代值$x$按降序排列，并且对于每个，尝试将其与最好的可能配对$y$这样$x \nmid y$和$y \nmid x$。 

由于我们总是从大到小处理值，因此我们可以动态地维护最佳可行的合作伙伴。 
6.尝试最好的三重。 

我们固定最大值$x$，然后尝试选择两个附加值$y, z$来自剩余的候选者，使得所有成对整除性约束都失败。 由于最多只需要两个元素，因此我们将搜索限制为顶级候选者并验证兼容性。 
7. 取所有有效结构中的最大值。 

### 为什么它有效

 我们最多选择三个元素的约束是关键的结构简化。 任何最优解都可以分为三种情况：大小 1、大小 2 或大小 3。对于每种情况，至少有一个元素必须是数组中最大的几个值之一； 否则用更大的兼容值替换它会在不破坏约束的情况下增加总和，或者由于可除单调性而保持有效。 

这允许将注意力限制在一个小的候选边界而不是所有元素上，并且除数结构确保兼容性检查保持快速。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXV = 200000

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        a = list(map(int, input().split()))

        freq = {}
        mx = 0
        for x in a:
            freq[x] = freq.get(x, 0) + 1
            if x > mx:
                mx = x

        vals = sorted(freq.keys(), reverse=True)

        best_single = mx

        best_pair = 0

        # Try all pairs in value space
        for i in range(len(vals)):
            x = vals[i]
            for j in range(i + 1, len(vals)):
                y = vals[j]
                if x % y != 0 and y % x != 0:
                    best_pair = max(best_pair, x + y)
                    break  # next x, since y is decreasing

        best_triple = 0

        # Try triples with top candidates
        top = vals[:min(60, len(vals))]

        for i in range(len(top)):
            x = top[i]
            for j in range(i + 1, len(top)):
                y = top[j]
                if x % y == 0 or y % x == 0:
                    continue
                for k in range(j + 1, len(top)):
                    z = top[k]
                    if x % z == 0 or z % x == 0:
                        continue
                    if y % z == 0 or z % y == 0:
                        continue
                    best_triple = max(best_triple, x + y + z)

        print(max(best_single, best_pair, best_triple))

if __name__ == "__main__":
    solve()
```该解决方案将问题分为三个独立的优化层，对应于选择一个、两个或三个元素。 单个案例是微不足道的。 配对情况利用排序值和早期停止。 三元组的情况仅限于有界候选集，因为只有最大值与最大化总和相关，并且检查所有三元组仅在这个缩减的子集上可行。 

可整除性检查直接对值进行，这避免了构建繁重的预处理结构。

 ## 边缘情况

 一个关键的边缘情况是最大的元素是长可分链的一部分。 例如，在像这样的集合中`2, 4, 8, 16`，选择最大值总是会阻止任何第二选择。 该算法通过与较小的兼容组合进行比较来处理此问题，而不是强制包含最大值。 

另一种边缘情况是最佳解决方案是三个中等值而不是一个大值加上其他值。 第二个示例演示了这种行为：最佳三元组避免了最大值，因为它阻碍了兼容性。 受限的三重枚举确保此类组合仍然在顶级候选者中进行检查。
