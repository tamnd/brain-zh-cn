 ## 解决方案
 ## 问题理解

 我们从一个字符串开始，想要构建一个恰好包含`k`不同的子序列。 添加长度的子序列`L`花费删除字符的数量，即`n - L`。 相同的子序列不能添加两次。 任务是最小化总成本，或报告没有足够的不同子序列。 

成本结构立即表明较长的子序列更可取。 长度的子序列`n`成本`0`， 长度`n-1`成本`1`， 等等。 如果我们知道每个长度存在多少个不同的子序列，则最佳策略是显而易见的：从长度中获取尽可能多的子序列`n`，然后从长度`n-1`，并继续向下，直到我们收集到`k`其中。 

简单版本有`n ≤ 100`，这允许动态规划大致`O(n²)`或者`O(n³)`运营。 枚举所有子序列是不可能的，因为长度为`100`有`2^100`子序列，远远超出任何可行的限制。 

有几种情况很容易处理不当。 

考虑```
1 2
a
```不同的子序列是`"a"`和`""`。 他们的成本是`0`和`1`，所以答案是```
1
```忘记空子序列的解决方案将错误地打印`-1`。 

另一个例子是```
3 8
aaa
```不同的子序列是```
"aaa"
"aa"
"a"
""
```由于许多删除模式产生相同的字符串，因此仅存在四个不同的子序列。 正确的输出是```
-1
```计算删除掩码而不是不同的字符串会错误地得出有八个选项可用的结论。 

第三个例子是```
4 5
abcd
```所有角色都是不同的。 有许多不同的子序列，最便宜的五个是```
abcd  cost 0
abc   cost 1
abd   cost 1
acd   cost 1
bcd   cost 1
```答案是```
4
```过早选择较短的子序列会不必要地增加总成本。 

## 方法

 暴力方法生成每个子序列，将结果字符串存储在一个集合中以删除重复项，按长度对它们进行排序，并取最长的`k`。 这个方法是正确的，因为它直接遵循定义。 问题是口罩的数量。 为了`n = 100`， 有`2^100 ≈ 10^30`子序列，这使得这种方法完全不可能。 

关键的观察是我们不需要子序列本身。 我们只需要知道每个可能的长度有多少个不同的子序列。 

假设我们从左到右处理字符串。 让`dp[i][j]`表示长度不同的子序列的数量`j`可以使用以位置结尾的前缀组成`i`。 如果我们附加`s[i]`，我们必须避免创建由先前出现的相同字符创建的重复项。 每个字符的最后一次出现使我们能够精确地减去那些重复项。 

这将指数枚举问题转变为多项式动态规划问题。 一旦知道了计数，我们就会贪婪地将子序列从较大的长度变为较小的长度，因为每增加一个删除的字符都会使成本增加一。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(2^n) | O(2^n) | 太慢了 |
 | 最佳| O(n²) | O(n²) | 已接受 |

 ## 算法演练

 1. 定义`dp[i][j]`作为长度不同的子序列的数量`j`可以使用第一个形成`i`人物。 
2. 初始化`dp[0][0] = 1`，因为空字符串有一个子序列，即它本身。 
3. 对字符进行一一处理。 对于职位`i`，首先复制所有值`dp[i-1][j]`，表示不使用新字符的子序列。 
4. 对于每个长度`j ≥ 1`，将当前字符附加到所有不同长度的子序列`j-1`来自之前的前缀。 这有助于`dp[i-1][j-1]`。 
5. 如果当前字符之前出现过，则将其之前的位置设为`p`。 将当前字符附加到该位置之前已存在的子序列`p`创建重复项。 减去`dp[p-1][j-1]`来自贡献。 

减法精确地删除了使用该字符的较早出现时已生成的子序列。 

1. 将当前位置存储为该字符的最新出现位置。 
2.填表后，`dp[n][j]`给出长度不同的子序列的数量`j`。 
3、从长度开始`n`并向下移动，在同时获取尽可能多的子序列`k > 0`。 
4.如果我们采取`x`长度子序列`j`，他们对答案的贡献是```
x × (n - j)
```1.如果考虑长度之后`0`我们还有`k > 0`, 少于`k`存在不同的子序列，因此打印`-1`。 

### 为什么它有效

 对于每个前缀和每个长度，`dp[i][j]`只计算一次不同的子序列。 每当一个字符再次出现时，唯一产生的重复子序列是该字符的最后一次出现来自前一个副本的子序列。 减去前一次发生之前的贡献就可以精确地删除那些重复项，而不会删除任何其他内容。 

由于成本随着子序列长度的增加而降低，因此任何最佳解决方案都必须在考虑较短的子序列之前使用尽可能多的较长子序列。 因此，贪婪收集阶段产生最小的总成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
s = input().strip()

dp = [[0] * (n + 1) for _ in range(n + 1)]
dp[0][0] = 1

last = [-1] * 26

for i in range(1, n + 1):
    c = ord(s[i - 1]) - ord('a')

    for j in range(n + 1):
        dp[i][j] = dp[i - 1][j]

    prev = last[c]

    for j in range(1, i + 1):
        add = dp[i - 1][j - 1]
        if prev != -1:
            add -= dp[prev][j - 1]
        dp[i][j] += add

    last[c] = i - 1

ans = 0

for length in range(n, -1, -1):
    take = min(k, dp[n][length])
    ans += take * (n - length)
    k -= take

if k > 0:
    print(-1)
else:
    print(ans)
```桌子有尺寸`(n+1) × (n+1)`。 排`i`代表第一个`i`人物。 每一行都从复制前一行开始，因为之前存在的每个子序列在添加新字符后仍然存在。 

微妙的部分是减法。 假设当前字符之前出现在索引处`prev`。 通过扩展在位置之前已经存在的东西而形成的任何子序列`prev`当使用较早的事件时已经创建了。 减法`dp[prev][j-1]`完全删除那些重复项。 

贪婪阶段从长度开始`n`，因为这些子序列的成本最低。 向下移动可保证总成本最低。 

Python 中不存在整数溢出问题。 在简单版本中，不同子序列的总数永远不会超过`2^100`，Python 自然可以处理。

def solve():
    input = sys.stdin.readline

    n, k = map(int, input().split())

    dp[0][0] = 1

        c = ord(s[i - 1]) - ord('a')

        for j in range(n + 1):

                add -= dp[prev][j - 1]
            dp[i][j] += add

        last[c] = i - 1

    ans = 0
    k = int(k)

        take = min(k, dp[n][length])
        ans += take * (n - length)
        k -= take

    if k > 0:

    else:
        print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    solve()
    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

 ## 边缘情况

 考虑```
1 2
a
```DP 计算一个长度子序列`1`和长度之一`0`。 贪婪阶段两者兼而有之。 他们的成本是`0`和`1`，给出答案`1`。 空子序列自然由以下方式处理`dp[0][0]=1`。 

现在考虑```
3 8
aaa
```该表以```
length 3 : 1
length 2 : 1
length 1 : 1
length 0 : 1
```尽管有八个删除掩码，但许多都会产生相同的字符串。 使用所有四个不同的子序列后，`k`保持正数，因此算法正确打印`-1`。 

最后，考虑```
4 5
abcd
```所有字符都不同，因此不会发生减法。 计数变为```
1, 4, 6, 4, 1
```对于长度`0`通过`4`。 贪婪阶段选择一个长度的子序列`4`和四个长度`3`, 生产总成本`4`，这是可能的最小值。
