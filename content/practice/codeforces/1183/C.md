 ## 解决方案
 ## 问题理解

 我们正在模拟一系列精确的$n$游戏轮流进行。 Vova 随时都有电量$k$，并且每一回合他必须选择减少冲锋的两个动作之一。 

就电池损耗而言，一种操作更便宜，但只能在电池电量足够高时使用。 另一种动作成本较高，但要求较弱，可以更频繁地使用。 目标是完成所有$n$转动，同时绝不让电池在任何转动后降至零或更低。 在所有有效策略中，我们希望最大化昂贵操作的使用次数。 

因此，问题不仅仅在于可行性，还在于在随时间变化的硬资源约束下最大化“更好”动作的数量。 

关键的困难在于每个回合的选择都会影响这两个动作的未来可用性。 没有全局推理的贪婪选择很容易失败，因为早期使用太多廉价的举动可能会在以后迫使非法状态，而使用太多昂贵的举动会减少你可以生存的总回合数。 

约束条件很大，有$q \le 10^5$和$n, k \le 10^9$。 这立即排除了任何模拟翻转。 任何解决方案都必须以对数或恒定时间计算每个查询的答案。 甚至$O(n)$每个测试用例是不可能的。 

当电池仅足以仅使用更便宜的减量来执行所有转弯时，就会出现微妙的边缘情况$b$。 即使这总体上是可能的，但根据订购，每轮后严格的积极性要求仍然可能会破坏可行性，因为一系列较大的减量可能会比预期更早地将电池推至零以下。 

例如，如果$k = 5$,$n = 2$,$a = 4$,$b = 3$， 虽然$5 - 3 - 3 = -1$，游戏是不可能的，但天真的推理“我们只需要总和≤k”可能会忽略中间状态必须保持正值。 

## 方法

 蛮力方法将尝试两种移动类型的所有可能分布$n$轮流，通过在每一步模拟电池来检查有效性。 在每一回合，我们都会分支到使用任一减量$a$或者$b$如果允许，并跟踪可行性。 这导致了指数级的可能性，大致$O(2^n)$，因为每个$n$轮流有两种选择。 即使通过电池限制进行修剪也不会改变最坏情况下的爆炸$k$很大。 

关键的观察是我们永远不需要模拟决策的确切顺序。 重要的是我们使用了多少次$a$- 移动与$b$-移动，因为电池只会减少，移动不会恢复能量。 该结构变成了一个资源分配问题：我们要选择最大数量的昂贵的$a$- 移动时仍然能够执行所有操作$n$步骤，将其余部分填充$b$- 必要时移动。 

思考这个问题的一个有用方法是从最乐观的场景开始。 如果我们假设每个回合都使用更便宜的缩减$b$，电池后$n$轮流将是$k - nb$。 这立即给出了一个可行性条件：如果$k \le nb$，即使是最好的情况序列也无法在整个游戏过程中保持电池电量充足。 

一旦可行性得到保证，我们想更换一些$b$- 与移动$a$-移动。 每次更换都会增加电池总消耗$a - b$。 然而，这些更换只有在电池在每一步之后都保持严格的正电状态时才有效，这有效地限制了我们在底座之上可以承受的“额外成本”$nb$消耗。 

问题归结为计算我们在基线之外还有多少额外的“预算”$nb$，以及大小的增量$a - b$可以符合该预算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(2^n)$|$O(n)$| 太慢了 |
 | 最佳 |$O(1)$每个查询|$O(1)$| 已接受 |

 ## 算法演练

 我们根据强制最低消耗和可选升级重写了流程。 

1. 如果我们总是使用更便宜的选项，计算可能的最小总消耗$b$。 这是$n \cdot b$。 如果这已经超过或等于$k$，则不存在有效序列。 原因是，即使是最好的策略也无法在所有步骤中保持电池正电。 
2. 如果可行，计算支付基准成本后剩余的可用预算：$k - n \cdot b$。 这代表了通过更换一些电池我们仍然可以承受多少额外的电池损耗$b$- 与移动$a$-移动。 
3. 每次我们更换一个$b$- 移动与$a$- 搬家，我们额外花费$a - b$电池单位。 这是改进动作的增量成本。 我们希望在不超出剩余预算的情况下最大限度地增加此类替换的数量。 
4. 因此最大替换次数为$\left\lfloor \frac{k - n b}{a - b} \right\rfloor$。 但是，我们不能超过总圈数$n$，所以我们取这个值和之间的最小值$n$。 
5. 最终答案是多少$a$- 移动，如果可行性失败，我们输出$-1$。 

### 为什么它有效

 任何有效的序列必须完全由$n$移动，每个贡献$a$或者$b$至总消费。 由于所有移动只会减少电池电量并且不存在恢复，因此移动顺序除了确保电池永远不会过早降至零之外，不会影响可行性。 只要总消耗严格小于，就可以满足严格的正向约束$k$，因为我们总是可以在不违反早期状态的情况下安排更高成本的移动。 这将问题转化为两个固定成本的简单预算分配问题。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        k, n, a, b = map(int, input().split())

        if k <= n * b:
            print(-1)
            continue

        # extra budget beyond baseline all-b moves
        extra = k - n * b

        # each a-move instead of b-move costs (a - b) extra
        ans = extra // (a - b)

        # cannot exceed number of turns
        if ans > n:
            ans = n

        print(ans)

if __name__ == "__main__":
    solve()
```该实现使用基线策略直接计算可行性，其中每一步都使用成本$b$。 一旦通过，它就会计算我们可以升级多少次$b$- 搬进一个$a$- 使用可用的额外预算进行搬迁。 

减法$k - n \cdot b$在具有固定整数大小的语言中使用 64 位算术必须小心地完成，但 Python 可以安全地处理大整数。 划分由$a - b$是整数楼层划分，与我们可以负担的全面升级的数量相匹配。 

## 工作示例

 ### 示例 1

 输入：$k = 15, n = 5, a = 3, b = 2$我们计算基准成本$n \cdot b = 10$。 剩余预算为$15 - 10 = 5$。 每次升级费用$a - b = 1$。 这样我们就可以升级5个动作。 

| 步骤| 基准成本| 额外预算| 升级 | 结果 |
 | --- | --- | --- | --- | --- |
 | 初始化| 10 | 10 5 | 0 | 可行|
 | 计算| - | 5 | - | 额外预算|
 | 划分| - | - | 5 | 5 个 a 动作 |

 我们得到答案5，这意味着所有动作都可以升级。 

这表明模型正确地识别出盈余预算直接转化为额外的更高成本的举措。 

### 示例 2

 输入：$k = 16, n = 7, a = 5, b = 2$基线成本是$14$。 剩余预算为$2$。 每次升级费用$3$。 无法升级。 

| 步骤| 基准成本| 额外预算| 升级 | 结果 |
 | --- | --- | --- | --- | --- |
 | 初始化| 14 | 14 2 | 0 | 可行|
 | 计算| - | 2 | - | 不足|
 | 划分| - | - | 0 | 0 个动作 |

 这表明即使游戏是可行的，但不可能对基准策略进行改进。

 ## 边缘情况

 当出现一种边缘情况时$k$正好等于$n \cdot b$。 在这种情况下，系统不会有任何懈怠。 任何替换的尝试$b$- 移动与$a$- 立即移动会破坏可行性。 算法正确返回$-1$，符合这样的事实：即使是最小的策略也不会留下积极的缓冲。 

另一个边缘情况出现时$a - b$与可用松弛相比较大。 即使总电池足以完成所有动作，也只能进行少数升级。 除法步骤确保我们不会过度计算，因为每次升级都会消耗剩余预算的固定离散量。 

最终的边界情况是$n$非常大但是$k$仅略高于$n \cdot b$。 尽管输入量很大，但答案变得非常小，并且恒定时间计算避免了对$n$超越算术。
