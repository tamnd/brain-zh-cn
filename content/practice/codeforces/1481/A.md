 ## 解决方案
 ## 问题理解

 我们在网格上的原点处给出了一个起点和一个目标坐标。 除此之外，我们还获得了一系列运动命令，由四个基本方向上的单位步骤组成。 每个命令按顺序执行，将位置沿相应方向精确移动一个单位。 

我们可以删除命令的任何子集，同时保留其余命令的相对顺序。 删除后，剩余的序列从原点开始从左到右执行。 问题是我们是否可以选择命令的子集，使得最终位置恰好成为目标坐标。 

所有测试用例中所有命令字符串的总长度最多为 100000 的限制意味着任何解决方案都必须处理每个字符一次或恒定次数。 任何尝试显式枚举子序列或模拟删除的方法都会立即失败，因为子序列的数量随着字符串长度呈指数增长。 

一个天真的但常见的陷阱是假设如果字符串总共包含足够的正确方向的移动，那么答案总是肯定的。 这是不正确的，因为顺序很重要，因为我们无法重新排列动作，只能删除它们。 例如，考虑从字符串“DDRRUU”到达 (1, 1)。 有足够的R和U动作，但是如果在所有U动作之后出现唯一的R，我们仍然可以选择它们并达到目标，因此顺序实际上并不限制超出计数可用性的可行性。 微妙之处在于，顺序永远不会阻碍可行性，因为删除可以跳过所有不相关的内容。 

另一个误导性的情况是认为我们必须以前缀形式精确匹配目标。 例如，如果我们贪婪地模拟，从“URDL”到达 (1, 1) 可能看起来不可能，但仅选择“UR”效果很好。 

真正的困难是认识到问题简化为从字符串中选择多个移动集，仅受保留顺序而非邻接性的约束。 

## 方法

 暴力解释将尝试每个字符子集，模拟生成的路径，并检查它是否落在目标上。 这探索了 2^n 种可能性，即使对于 n = 40 这也是不可行的，更不用说 n 达到 100000 了。这种方法的正确性很简单，因为它明确地检查所有有效删除，但其指数增长使其无法使用。 

关键的观察结果是，删除角色使我们可以完全自由地选择任何动作子集，但我们无法对它们重新排序。 由于顺序不影响最终坐标，因此只有方向计数很重要。 每个选定的角色都会独立地产生位移，因此最终位置仅取决于我们保留的 U、D、L 和 R 移动次数。 

为了达到(p_x, p_y)，我们必须确保删除后，净水平移动等于p_x，净垂直移动等于p_y。 这意味着至少需要 |p_x| 沿所需水平方向移动且至少 |p_y| 沿所需的垂直方向移动。 

因此，问题简化为检查字符串是否包含每个所需方向的足够出现次数。

 ## 算法演练

 我们独立处理每个测试用例。

1. 计算每个方向在字符串中出现的次数。 这为我们提供了 U、D、L 和 R 移动的可用供应，而无需考虑顺序。 这样做的原因是任何子集选择仅取决于可用性，而不取决于排列。 
2. 计算每个轴相对于目标坐标需要移动多少次。 如果 p_x 为正，我们需要 p_x 向右移动； 如果为负，我们需要 -p_x 左移。 对于具有向上和向下的 p_y 也是如此。 
3. 通过验证字符串是否在 p_x 为正时至少包含 p_x R 移动，或者在 p_x 为负时至少包含 -p_x L 移动来检查 x 轴上的可行性。 
4. 使用 U 和 D 计数对 y 轴执行相同的操作。 
5、如果两个轴都能独立满足，则输出YES，否则输出NO。 

### 为什么它有效

 每个移动都会独立地影响最终的位移，删除只会减少计数，而不会引入方向之间的相互作用。 由于最终位置是独立单位向量的总和，因此可行性仅取决于我们是否可以在每个所需方向上选择足够的向量。 任何排序约束都不能阻止有效的选择，因为任何不需要的前缀都可以简单地删除。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        px, py = map(int, input().split())
        s = input().strip()

        r = s.count('R')
        l = s.count('L')
        u = s.count('U')
        d = s.count('D')

        ok_x = (px >= 0 and r >= px) or (px < 0 and l >= -px)
        ok_y = (py >= 0 and u >= py) or (py < 0 and d >= -py)

        print("YES" if ok_x and ok_y else "NO")

if __name__ == "__main__":
    solve()
```实施直接遵循“只有方向才重要”的观察。 每个测试用例计算字符串上线性时间的四个计数，然后将它们与所需的位移分量进行比较。 

一个微妙的点是正确处理符号：正 x 对应于 R，负 x 对应于 L，类似地，y 对应于 U 和 D。混合这些条件会导致不正确的可行性检查。

 ## 边缘情况

 一种边缘情况是目标完全位于一个轴上，例如 (0, y)。 在这种情况下，水平移动是无关紧要的，只有 U 和 D 才重要。 该算法自然会处理这个问题，因为它只检查每个轴所需的方向。 

当字符串包含完全平衡的相反移动（例如相同数量的 L 和 R），但目标需要净移动时，会出现另一种边缘情况。 该解决方案不依赖于原始字符串的净位移，仅依赖于可用性，因此它正确地忽略了整个字符串中的抵消效应，并且仅关注选择可行性。
