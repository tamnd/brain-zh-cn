 ## 解决方案
 ## 问题理解

 一个频道有`n`订户。 当新帖子发布时，准确地说`a`订阅者在线，所以那些`a`人们立即阅读了这篇文章。 

之后，我们会收到一系列通知。 一个`'+'`意味着一些订阅者上线了，并且`'-'`意味着某些订阅者离线了。 我们知道该序列是有效的，但我们不知道每个通知引用的是哪个特定订阅者。 

问题是是否每个订阅者都曾在某个时刻阅读过该帖子。 

有三个可能的答案。`YES`意味着每个订阅者都必须阅读该帖子，无论通知涉及哪些人。`NO`意味着不可能将订阅者分配给让每个人都可以阅读帖子的通知。`MAYBE`意味着某些作业允许每个人阅读该帖子，而其他作业则不允许。 

限制非常小。 两个都`n`和`q`最多 100 个，最多 500 个测试用例。 即使是昂贵的模拟也能在限制范围内轻松完成。 挑战不在于性能，而在于正确推理通知揭示的信息。 

关键的困难在于我们永远不知道身份。 当某人上线时，该人可能是以前从未阅读过该帖子的订阅者，也可能是之前已经在线并在离线后返回的人。 

考虑以下示例：```text
n = 5
a = 4
s = "-+"
```最初有四个人阅读了这篇文章。 

之后`-`，一个人离开。 

之后`+`，要么是同一个人返回，要么是第五个订阅者第一次上线。 

两种解释都是有效的。 在一种情况下，所有五个订阅者都阅读了该帖子，而在另一种情况下，只有四个订阅者阅读了该帖子。 正确答案是`MAYBE`。 

另一个容易犯的错误是只看最终的在线订户数量。```text
n = 5
a = 2
s = "++-"
```在线计数变为 2 → 3 → 4 → 3。 

迄今为止在线订阅者的最大数量仅为 4，因此至少有一名订阅者从未有机会上线并阅读该帖子。 答案是`NO`。 

当每个人一开始就已经在线时，就会出现不同的边缘情况。```text
n = 5
a = 5
s = "--+"
```所有订阅者在帖子发布后立即阅读该帖子。 未来的通知并不重要。 答案是`YES`。 

## 方法

 暴力方法会尝试准确跟踪哪些订阅者已经阅读了该帖子。 每当一个`'+'`发生这种情况时，我们需要决定哪个离线订阅者上线。 由于身份未知，每个通知都可能分支为多种可能性。 

可能的状态数量随着通知数量呈指数增长。 即使只有 100 个通知，这样的搜索也是完全不切实际的。 

关键的观察是我们实际上并不关心身份。 我们只需要知道是否可能、不可能或保证所有订阅者都已阅读该帖子。 

想想有多少人曾经有机会阅读过这篇文章。 

最初，`a`订阅者已经阅读过。 

每一个`'+'`通知可能会介绍一位自帖子发布以来从未在线过的新订阅者。 如果我们乐观地假设每一个`'+'`引入新的未读订阅者，则最大可能的读者数为：```text
a + number_of_pluses
```上限为`n`。 

如果这个乐观计数小于`n`，那么某些订阅者永远无法阅读该帖子。 答案是`NO`。 

现在考虑一下何时保证所有订阅者都阅读了该帖子。 

如果任意时刻在线订阅人数达到`n`，那么每个订阅者必须在那一刻同时在线。 由于网上的任何人都会阅读该帖子，因此所有订阅者都肯定已阅读它。 一旦发生这种情况，以后的通知就无法改变这一事实。 

所以我们模拟在线计数。 如果它曾经达到`n`，答案是`YES`。 

如果这两个条件都不适用，则可以覆盖所有订阅者，但不强制。 答案是`MAYBE`。

 |---|---|---|---|
 | 蛮力 | 指数为`q`| 指数| 太慢了 |
 | 最佳| O(q) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从当前在线数等于`a`。 

2. 数一数有多少个`'+'`通知出现在字符串中。 

3.如果`a + plus_count < n`， 输出`NO`。 

这是可能阅读该帖子的最大数量的不同订阅者。 如果仍然低于`n`，覆盖所有订阅者是不可能的。 

4. 否则，通过通知序列模拟在线计数。 

5. 对于每个`'+'`，将当前在线数加一。 

6. 对于每个`'-'`，将当前在线数减一。 

7、每次更新后，检查当前在线数是否等于`n`。 

如果是，则输出`YES`。 

8. 如果模拟完成后还没有达到`n`， 输出`MAYBE`。 

### 为什么它有效

 第一次检查确定可能性。 最初`a`人们已经阅读了这篇文章。 一个`'+'`notification 是唯一可以创建新读者的事件，每个此类事件最多可以添加一个以前未读的订阅者。 因此`a + plus_count`是可以阅读该帖子的订阅者数量的上限。 如果该界限低于`n`，成功是不可能的。 

为了保证成功，请观察在线计数何时恰好变为`n`，所有订阅者同时在线。 每个订阅者当时都必须阅读该帖子。 由于阅读是永久性的，所以答案是立即的`YES`。 

如果有可能成功，但我们从未达到在线计数`n`，存在这样的解释：每个`'+'`引入了新的订户和解释，其中一些`'+'`事件对应于返回的订阅者。 两种结果都是可行的，所以正确答案是`MAYBE`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, a, q = map(int, input().split())
    s = input().strip()

    if a + s.count('+') < n:
        print("NO")
        continue

    cur = a
    guaranteed = (cur == n)

    for ch in s:
        if ch == '+':
            cur += 1
        else:
            cur -= 1

        if cur == n:
            guaranteed = True

    if guaranteed:
        print("YES")
    else:
        print("MAYBE")
```第一部分计算可能阅读该帖子的不同订阅者的最大数量。 如果该值低于`n`，我们立即知道答案是`NO`。 

否则，我们模拟在线计数。 我们不跟踪身份，因为保证条件仅取决于计数是否达到`n`。 

变量`guaranteed`商店我们是否已经看到所有订阅者同时在线。 它还必须初始化为`cur == n`因为在任何通知到达之前每个人都可能已经在线。 

模拟只是应用每个通知并检查当前计数是否变为`n`。 

对于无效状态不需要特殊处理，因为该问题保证通知顺序一致。 

## 工作示例

 ### 示例 1

 输入：```text
n = 5
a = 0
s = "++++-++"
```首先，计算可能性：```text
a + pluses = 0 + 6 = 6 ≥ 5
```所以`NO`是不可能的。 

| 步骤| 活动 | 在线计数 |
 |---|---|---|
 | 开始| - | 0 |
 | 1 | + | 1 |
 | 2 | + | 2 |
 | 3 | + | 3 |
 | 4 | + | 4 |
 | 5 | - | 3 |
 | 6 | + | 4 |
 | 7 | + | 5 |

 计数达到 5，因此所有订阅者同时在线。 

输出：```text
YES
```该迹线表明了保证条件。 一旦计数达到`n`，每个订阅者肯定都读过这篇文章。 

### 示例 2

 输入：```text
n = 5
a = 4
s = "-+"
```可能性检查：```text
a + pluses = 4 + 1 = 5
```因此，覆盖所有订阅者是可能的。 

| 步骤| 活动 | 在线计数 |
 |---|---|---|
 | 开始| - | 4 |
 | 1 | - | 3 |
 | 2 | + | 4 |

 计数永远不会达到 5。 

输出：```text
MAYBE
```这个痕迹表明了为什么确定性是不可能的。 决赛`+`可能是失踪的第五位订阅者，也可能是之前已经读过该帖子的人。

 ## 边缘情况

 ### 发布时每个人都在线

 输入：```text
1
5 5 3
--+
```该算法开始于`cur = 5`，这已经等于`n`。 变量`guaranteed`变成`True`在处理任何通知之前。 

即使订阅者后来离线，他们也已经阅读了该帖子。 输出是：```text
YES
```仅在处理通知后检查计数的解决方案可能会错过这种情况。 

### 没有足够的“+”通知

 输入：```text
1
5 2 3
++-
```我们计算：```text
2 + 2 = 4
```读者的最大可能数量仅为四人。 任何身份分配都无法使所有五个订阅者都阅读该帖子。 

该算法立即输出：```text
NO
```无需任何模拟。 

### 可能但不确定

 输入：```text
1
5 4 2
-+
```可能性检查给出：```text
4 + 1 = 5
```所以成功是可能的。 

网上人数为：```text
4 -> 3 -> 4
```计数永远不会达到 5，因此我们不能保证所有订阅者都已阅读该帖子。 

一种有效的解释是，同一个订阅者离开并返回，只提供了四个读者。 另一个是失踪的订户最后上线，给了五个读者。 

算法正确输出：```text
MAYBE
```
