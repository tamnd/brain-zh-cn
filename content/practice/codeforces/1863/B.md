 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 的数字排列，我们希望将其转换为恒等排列，其中每个值位于其匹配的索引位置。 唯一允许的移动是一种稳定分区：选择一个阈值 x，然后通过按当前相对顺序取出所有小于 x 的元素对数组重新排序，然后是所有大于或等于 x 的元素，再次保留其相对顺序。 

此操作不允许任意重新排列。 它只允许我们根据值阈值重复分割序列，同时保留每个组内的内部顺序。 目标是确定对排列进行完全排序所需的此类拆分的最小数量。 

测试中的约束 n 高达 100,000，总和也高达 100,000，这意味着我们每个测试用例都需要一个线性或接近线性的解决方案。 任何二次方的事情，例如显式模拟每个操作或重复重建数组，都将无法生存。 

一个微妙的方面是，操作取决于值，而不是仓位，而是影响全局的仓位。 天真的直觉可能是我们正在“逐渐排序”，但每个操作都是单个分区的限制使得该过程比典型的排序更加结构化。 

经常误导的边缘情况包括已经排序的数组、完全反转的数组以及局部顺序看起来部分排序但全局结构仍然需要多个分区的排列。 例如，像这样的排列`[2, 1, 3, 4]`已经几乎排序，但仍然只需要一次操作，因为单个阈值分割可以正确隔离 1 和 2。 

另一个陷阱是假设我们可以在每次操作中修复一个元素。 但事实并非如此，因为如果多个放错位置的元素与阈值分割对齐，则一项操作可以同时纠正这些元素。 

## 方法

 暴力策略将直接模拟该过程。 从当前排列开始，尝试从 2 到 n 的每一个可能的 x，应用稳定分区操作，并递归搜索最小步骤，直到到达排序数组。 每个操作的成本为 O(n)，并且状态空间都是排列，使得最坏情况的大小为阶乘。 即使限制在状态上的 BFS 也会给出 n! 原则上说这是不可行的。 

关键的观察结果是，该操作本质上是构建价值阈值的层次结构。 每个操作都在值空间中选择一个切点，而不是位置空间。 如果我们考虑最终排序的数组必须如何出现，每个值最终都必须与其之前出现的较大值分开。 

关键的结构见解是扫描从 n 到 1 的值，并计算连续值的“位置顺序”以特定方式中断的次数。 在正确的最终状态中，值 1 到 n 按位置递增顺序出现。 连续值 i 和 i+1 之间的任何反转都意味着它们当前位于不同的相对块中，如果不进行将它们分开的操作，则无法修复这些块。 

每个操作可以将多个按值顺序相邻的正确段合并到一个排序结构中，但它无法一次修复所有中断。 这导致了这样一种想法：答案是由 i+1 的位置在 i 之前出现的次数决定的，这迫使至少一个新的操作边界。 

因此，我们不是模拟操作，而是测量排列相对于递增值顺序的碎片程度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n!) | O(n!) | 太慢了 |
 | 最优值顺序扫描 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 构建一个数组 pos，其中 pos[v] 给出排列中值 v 的索引。 

这将问题从处理位置转变为纯粹处理价值顺序约束。 
2. 将计数器段初始化为1，表示我们必须形成至少一个连续的结构。 
3. 将 v 从 1 迭代到 n-1，比较 pos[v] 和 pos[v+1]。 

每次 pos[v] 大于 pos[v+1] 时，意味着 v 在排列中出现在 v+1 之后，打破了递增结构。 
4. 每当发生此类中断时，将段加 1。 

这反映出 v 和 v+1 不能属于同一个“已经正确排序的块”，因此至少需要一个额外的操作来分离和修复排序。 
5. 输出段减1作为答案。 

减一是因为在应用任何操作之前初始数组已经被视为一个段，并且每个检测到的中断都会增加段之间所需合并的数量。 

### 为什么它有效

 每个具有阈值 x 的操作将值分为两个单调组：小于 x 的值和至少 x 的值，保留内部顺序。 这意味着解决排序顺序中的连续值之间的无序问题的唯一方法是确保最终所有较早的值按位置顺序出现在较晚的值之前。 

每次 pos[v] > pos[v+1] 时，对 (v, v+1) 的位置顺序都会反转，迫使它们进入不同的结构层，如果没有至少一个操作边界，这些结构层就无法统一。 这种结构中断的数量决定了需要多少次独立合并，并且在最好的情况下每个操作可以恰好减少一层碎片。 

因此，这些中断的计数直接对应于所需的最小操作次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        
        pos = [0] * (n + 1)
        for i, v in enumerate(p):
            pos[v] = i
        
        segments = 1
        for v in range(1, n):
            if pos[v] > pos[v + 1]:
                segments += 1
        
        print(segments - 1)

if __name__ == "__main__":
    solve()
```实现的核心是位置反转数组。 通过将值转换为位置，我们可以避免完全模拟任何操作。 

v 上的循环检查连续值是否以正确的从左到右顺序出现。 每次违规都会增加所需结构段的数量。 最终的减法说明了初始段基线。 

必须小心正确地构建 pos，因为这里的索引错误会完全颠倒逻辑。 此外，由于存在多个测试用例，因此必须针对每个用例重建所有阵列以避免泄漏。 

## 工作示例

 ### 示例 1

 输入排列：`[2, 1, 3, 4]`我们计算位置：

 位置[1] = 1，位置[2] = 0，位置[3] = 2，位置[4] = 3

 | v | 位置[v] | 位置[v+1] | 休息？ | 细分 |
 | ---| ---| ---| ---| ---|
 | 1 | 1 | 0 | 是的 | 2 |
 | 2 | 0 | 2 | 没有| 2 |
 | 3 | 2 | 3 | 没有| 2 |

 答案是 2 - 1 = 1。 

这显示了 1 和 2 之间的一次反转，需要一次操作。 

### 示例 2

 输入排列：`[3, 2, 1]`职位：

 位置[1] = 2，位置[2] = 1，位置[3] = 0

 | v | 位置[v] | 位置[v+1] | 休息？ | 细分 |
 | ---| ---| ---| ---| ---|
 | 1 | 2 | 1 | 是的 | 2 |
 | 2 | 1 | 0 | 是的 | 3 |

 答案是 3 - 1 = 2。 

每个相邻的反转都贡献一个单独的结构分割要求，反映排列是完全反转的。

 ## 边缘情况

 对于已经排序的排列，例如`[1, 2, 3, 4]`，每个连续的对都满足 pos[v] < pos[v+1]，因此不会发生分段中断，并且算法输出为零。 这符合不需要任何操作的事实。 

对于完全相反的排列，例如`[n, n-1, ..., 1]`，每个相邻对的位置顺序反转，因此段计数变为 n，产生答案 n-1。 每次反转都会强制进行不同的结构分离，并且算法会正确累积所有所需的操作。 

对于具有单个本地交换的排列，例如`[1, 3, 2, 4]`，只有 (2, 3) 对创建中断，产生单个所需操作。 扫描恰好检测到一个位置反转，算法将其直接转换为一个分区步骤。
