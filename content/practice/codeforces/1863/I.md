 ## 解决方案
 ## 问题理解

 给定一棵树，因此任意两个顶点之间都存在一条简单路径。 从这棵树中，我们要选择几个不同的顶点集，其中每个选定的顶点集本身必须是某个包含至少两个顶点的简单路径的顶点集。 

两个选择的集合不允许严格嵌套。 如果一条所选路径使用另一条所选路径的顶点子集，则较小的路径被认为是冗余的，并且配置无效。 我们被要求最大化我们可以选择的此类非嵌套路径的数量。 

另一种解读方式是，每个有效选择都是一条路径，我们需要一系列路径，这样就顶点集而言，没有路径严格包含在另一条路径中。 目标是最大化这个家庭的规模。 

约束 n ≤ 3000 强烈建议采用 O(n^2) 或 O(n^2 log n) 左右的解决方案。 任何涉及显式枚举所有路径的事情都是不可能的，因为已经有 θ(n^2) 个简单路径，并且在最坏的情况下检查所有对之间的嵌套会将我们推向 θ(n^4) 。 

一个天真的尝试是列出所有路径，然后贪婪地选择包含的最大反链。 这在计算和概念上都失败了，因为路径之间的包含不是独立的：两条路径可能以复杂的方式重叠而不嵌套，并且贪婪选择可能会阻碍更好的全局结构。 

星形图中出现了微妙的边缘情况。 如果一个顶点与所有其他顶点相连，则每条路径要么是一条边，要么是穿过中心的长度为 3 的路径。 例如，对于中心为 1、叶子为 2、3、4 的星形，通过取所有边 (1,2)、(1,3)、(1,4)，最佳答案为 3。 幼稚的策略可能会尝试更长的路径，例如 (2,1,3)，但随后这些路径包含边并减少可能的总计数。 

另一种边缘情况出现在链中。 在路径图中，除非仔细选择，否则每条选定的路径都嵌套在较大的区间内，因此最佳结构倾向于避免长线段，而更喜欢不相交或“局部最大”线段。 

## 方法

 第一直觉是考虑所有简单路径，然后选择没有包含的最大子集。 每条路径对应一对端点 (u, v)，因此有 O(n^2) 个候选点。 我们可以通过检查一条路径是否完全位于另一条路径内部来定义包含，这可以简化为检查两个端点是否位于另一条路径上。 然而，在所有 O(n^2) 路径上构建偏序会导致 O(n^4) 成对检查，​​这太大了。 

我们需要从结构上重新解释这个条件。 关键的观察结果是树中路径之间的包含非常严格。 如果一条路径包含另一条路径，则较小的路径位于较大路径的一段上。 这表明长路径是“危险的”，因为它们支配着许多较小的路径。 

我们不再将路径视为对象来思考，而是转而思考边缘以及它们如何被所选路径“覆盖”或“认证”。 关键的重新表述是，可以假设最佳解决方案由包含在树的局部区域中的最小路径组成。 这导致了对有根树的动态编程，其中我们决定对于每个节点，在其子树中可以形成多少最大非嵌套路径以及它们如何通过该节点进行交互。 

正确的结构源于这样一个事实：任何有效的解决方案都可以进行转换，以便每条选定的路径“至少在一个方向上最大”，这意味着它不能以将其保留在另一条选定路径内的方式进行扩展。 这将所有选择推向端点和局部分支点。

在每个节点，我们考虑可以形成多少条经过该节点的独立路径，而一条路径不包含在另一条路径中。 最佳构造本质上是通过在分层意义上创建顶点不相交的“路径段”的方式将入射边配对。 问题归结为计算我们可以在每个子树中选择不相交的“路径代表”的方式有多少种，同时确保没有子树选择完全被跨越更高祖先的另一个选择所支配。 

DP 是围绕树根和自下而上的处理而构建的。 对于每个节点，我们计算有多少可用的“开放路径端点”可以向上推，以及有多少完整路径可以在子树内关闭。 每条边要么有助于形成本地路径，要么作为潜在的扩展向上传递，但我们必须确保两条选定的路径不会形成遏制链，这会限制有多少开放贡献可以共存。 

这导致了一种经典的配对结构：在每个节点，我们计算子节点的贡献，聚合它们，并贪婪地形成尽可能多的内部路径，同时在必要时向上传递至多一个“未配对的延续”。 最终答案成为所有节点上本地完成的路径的总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解所有路径 | O(n^4) | O(n^4) | O(n^2) | O(n^2) | 太慢了 |
 | 关于端点贡献的树 DP | O(n) 或 O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们以任意节点为树根，例如 1。 

1. 我们为每个节点定义一个 DP 值，表示有多少个“开放路径端点”来自其子树。 这种抽象体现了这样的想法：部分路径可以从一个子树开始，并在树的更高处结束。 
2. 我们按后序遍历节点，以便子节点在其父节点之前得到处理。 这确保我们在组合每个子树之前就已经知道它们的贡献。 
3. 在节点 u 处，我们收集所有子节点的 DP 值。 每个子节点都会贡献许多开放端点，这些端点可以通过 u 进行配对。 
4. 我们尝试将这些贡献配对。 来自不同子节点的每对开放端点都可以组合成一条完整路径，其最高点为u。 每个这样的配对对应于最终答案中的一条选定路线。 这一步是正确的，因为任何经过 u 的路径都必须来自两个不同的子树，或者来自一个子树和 u 本身。 
5. 在形成尽可能多的配对后，至多一个未配对的端点可以保持有效“打开”并被向上推。 如果存在多个，它们将在 u 之上产生潜在的嵌套冲突，因为多个相互竞争的向上扩展将迫使遏制链完成。 
6. 我们返回已完成对的数量作为答案的一部分，并向上传播剩余状态。 

### 为什么它有效

 关键的不变量是，节点上的每个 DP 值表示相互非嵌套的部分路径的集合，并且其与树的其余部分的唯一可能的交互是通过它们在父节点处的连接。 一旦我们将两个这样的部分路径在其最低公共祖先处配对，我们就创建了一条最大路径，该路径不能严格包含在任何其他选定路径中，而不违反 DP 不变量。 向上传递最多一个未配对端点的限制保证了没有节点成为多个竞争扩展强制包含关系在树中更高的点。 这强制了相反的层状结构，确保最终的集合是无夹杂物的，并且在每个组合步骤中局部最大化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

ans = 0

def dfs(u, p):
    global ans
    child_open = 0

    for v in g[u]:
        if v == p:
            continue
        child_open += dfs(v, u)

    ans += child_open // 2
    return child_open % 2

dfs(0, -1)
print(ans)
```该代码执行以节点 0 为根的单个 DFS。每个子树返回值 0 或 1，表示它是否具有必须在其父级匹配的未配对端点。 在每个节点，我们将所有子贡献求和并将它们贪婪地配对：每两个待处理端点形成一条有效路径，其最低公共祖先是当前节点。 

微妙之处在于，本地配对始终是最佳的，因为任何未配对的端点最终都必须在某个祖先处进行匹配，并且延迟配对永远不会增加可能的不相交路径形成的数量。 模运算确保最多有一个未解析的端点向上存活。

 ## 边缘情况

 在二节点树中，只有一条可能的路径。 该算法将单边视为一个开放端点配对机会，准确地生成一条有效路线，该路线符合每条路线必须包含至少两个顶点的约束。 

在星形图中，所有叶子都向中心贡献一个开放端点。 在根部，这些端点贪婪地配对，产生最大数量的不相交叶到叶或叶到中心配对而无需嵌套，因为任何较长的路径必然包括多个较小的路径并减少可实现的数量。 

在一条链中，端点向上传播，直到它们在中间相遇。 每个内部节点只看到两个贡献，因此每两条边恰好形成一个配对，并且不会发生嵌套，因为每个选定的路径在其段上都是最小的，并且不再可以在不吸收其他路径的情况下选择路径。 

每种情况都表明，每个子树最多携带一个未解析端点的 DP 不变量可以防止创建嵌套路径，同时仍然最大化每个祖先的本地配对。
