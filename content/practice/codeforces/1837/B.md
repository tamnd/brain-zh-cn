 ## 解决方案
 ## 问题理解

 我们得到一个字符串，它对数组的相邻元素之间的局部比较进行编码。 每个字符描述下一个元素是否必须大于或小于当前元素。 任务不是构造任何有效的数组，而是构造一个使用尽可能少的不同值的数组，同时仍然尊重所有这些比较。 

思考这个问题的一个有用方法是，我们尝试为一条线上的位置分配高度，其中每一步都迫使我们向上或向下。 我们可以重用值，但前提是这样做不会违反严格的不平等要求。 

输出是实现遵循给定的上下序列的“行走”所需的最小数量的不同整数。 

约束足够小，每个测​​试用例的 O(n²) 想法已经可以轻松通过，因为 n 最多为 100，t 最多为 500。这强烈表明，我们预计不会在线性或二次扫描之外进行渐近优化。 真正的挑战是理解什么结构决定了不同值的最小数量。 

天真的尝试可能会尝试显式构造数组或从左到右贪婪地赋值，同时尽可能重复使用数字。 这很快就会变得脆弱，因为本地重用决策可能会以难以预测的方式阻止未来的重用。 

第二个天真的想法是通过对小范围整数进行回溯来尝试所有可能的分配。 即使只有 100 个位置，分支因子实际上也是无界的，并且对不等式的约束意味着我们将探索一个大的标签组合空间。 

当字符串交替时，会出现更微妙的失败情况，例如“<><><><”。 贪婪的方法可能会尝试重复重用两个值，但事实证明，这会导致振荡，如果分配不当，则需要引入比预期更多的不同值。 正确答案取决于全局结构，而不是局部决策。 

## 方法

 关键的观察结果是，问题实际上并不在于绝对值，而在于相对排序约束。 我们只关心连续元素是向上还是向下，这意味着实际的数字可以被认为是分配给向上和向下移动的路径的标签。 

不同值的最小数量对应于一致地实现整个序列所需的最小“级别”数量。 每次上升时，我们都需要确保在必要时可以移动到更高的未使用级别，而每次下降时，我们都会向相反的方向反映该约束。 

重要的结构见解是任何有效的分配都可以转移和压缩，以便值与步行的高度相对应。 成本就是访问的不同高度的数量。 这将问题简化为分析类似前缀和的结构的极值范围。 

如果我们将“<”解释为+1，将“>”解释为-1，并跟踪运行余额，则该运行总和的最高值和最低值之间的最大差值决定了需要多少个不同的值。 直观地说，如果步行曾经比起点低 k 步，并且以某种移动形式比起点高 k 步，那么我们需要 k+1 个不同的级别来容纳它。 

更精确的理解方法是考虑每个位置对应于由累积移动确定的整数线上的一个点。 不同值的最小数量是最佳压缩表示中不同高度的数量，这正是可达前缀极值的范围。 

显式分配值的蛮力想法失败了，因为它没有意识到只有相对排名很重要。 一旦我们切换到跟踪前缀极值，每个测试用例的解决方案就变成线性的。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力建造| O(2^n) 或更糟 | O(n) | 太慢了 |
 | 最优前缀极值跟踪 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将比较字符串转换为定向步骤序列，将每个字符视为将影响运行位置的移动约束。 
2. 将运行计数器初始化为零，它代表假设结构中的当前“高度”。 
3. 从左到右遍历字符串。 当遇到“<”时，将计数器加 1。当遇到“>”时，将计数器减 1。这模拟了数组的一种有效压缩表示。 

这样做的原因是我们还没有分配实际值，而是构建一个尊重每个约束的相对排序结构。 
4. 更新运行计数器时，跟踪遍历过程中达到的最小值和达到的最大值。 
5. 答案是本次行走覆盖的范围大小，计算公式为`max_value - min_value + 1`。 

这个范围表示如果我们以最佳方式压缩结构以使每个高度对应一个唯一值，则需要多少个不同的整数标签。 

### 为什么它有效

 任何有效的数组都会引发一系列相对比较，可以通过重复分配与符号一致的相邻差异来映射到整数游走。 通过移动它来压缩该步行，使最小值变为零不会改变有效性，但会最小化不同值的数量。 不同值的数量恰好是访问的整数级别的数量，它等于最小和最大前缀位移之间的范围。 没有替代分配可以缩小此范围，因为任何重用值的尝试都将强制违反字符串的至少一个段中的严格排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        cur = 0
        mn = 0
        mx = 0

        for ch in s:
            if ch == '<':
                cur += 1
            else:
                cur -= 1
            mn = min(mn, cur)
            mx = max(mx, cur)

        print(mx - mn + 1)

if __name__ == "__main__":
    solve()
```该代码维护单个运行位置并根据每次比较进行更新。 在此遍历过程中观察到的最小值和最大值定义了诱导结构的跨度。 最终答案是根据该跨度的大小计算的。 该实现小心地将计数器初始化为零，因为数组在应用任何比较之前启动。 

## 工作示例

 ### 示例 1：`<<>>`我们跟踪运行值及其极值。 

| 步骤| 查尔 | 当前| 最小 | 最大|
 | ---| ---| ---| ---| ---|
 | 0 | 开始 | 0 | 0 | 0 |
 | 1 | < | 1 | 0 | 1 |
 | 2 | < | 2 | 0 | 2 |
 | 3 | > | 1 | 0 | 2 |
 | 4 | > | 0 | 0 | 2 |

 最终范围是 2 - 0 + 1 = 3。 

该迹线表明，即使我们最终返回到零，2 的中间峰值也会在任何有效构造中强制产生三个不同的级别。 

### 示例 2：`>>>>`| 步骤| 查尔 | 当前| 最小 | 最大|
 | ---| ---| ---| ---| ---|
 | 0 | 开始 | 0 | 0 | 0 |
 | 1 | > | -1 | -1 | 0 |
 | 2 | > | -2 | -2 | 0 |
 | 3 | > | -3 | -3 | 0 |
 | 4 | > | -4 | -4 | 0 |

 最终范围是 0 - (-4) + 1 = 5。 

这种情况表明，单调递减序列迫使所需的不同值线性增加，因为每个步骤都会将构造推向新的最小值。

 ## 边缘情况

 单字符字符串暴露了算法是否正确处理基本初始化。 对于“<”，运行值变为 1，因此范围为 [0,1]，给出答案 2。对于“>”，运行值变为 -1，因此范围为 [-1,0]，再次给出 2。算法自然地处理这两种情况，无需特殊大小写，因为极值初始化为零。 

像“>>>>>>”这样的完全递减的字符串不断地将运行值向下推。 最小值不断减小，而最大值保持为零，因此范围呈线性增长。 每一步都会引入一个新的最小值，最终的答案反映了达到的总深度。 

诸如“<><><><”之类的交替字符串使运行值在两个相邻级别之间振荡。 最小值和最大值很快稳定在 0 和 1，因此结果仍然是 2。这证实了振荡不会将所需的不同值增加到超过 2，因为步行永远不会扩展其范围。
