 ## 解决方案
 ## 问题理解

 我们被要求模拟蚂蚁在二维整数网格上的扩散。 最初，所有 _n_ 只蚂蚁都放置在原点 (0, 0) 处。 时间以离散的分钟为单位进行，每分钟包含四只或更多蚂蚁的任何单元都会释放四只蚂蚁为一组的蚂蚁，将一只蚂蚁发送到四个主要邻居中的每一个：左、右、上、下。 少于四只蚂蚁的单元不会移动。 我们被要求确定在无法进行更多移动后指定坐标处的蚂蚁数量。 

输入给出_n_（开始时的蚂蚁数量）和_t_查询，每个查询询问特定网格单元中蚂蚁的最终数量。 网格坐标可能非常大，最大可达 ±10^9，这会妨碍显式表示整个网格。 蚂蚁的数量限制在 30,000 只，这是一个适度的数字，这表明活跃细胞的总数不会爆炸超过可管理的规模。 查询可能会重叠，因此我们可能需要多次回答同一个单元格。 

边缘情况包括有零只蚂蚁，其中每个查询都应返回 0，或者蚂蚁很少，其中没有单元格达到四只蚂蚁。 另一个微妙的情况是，当所有蚂蚁最终都定居在原点附近时，因此远处的查询点应该为零，即使它们是有效的坐标。 

## 方法

 蛮力方法很简单：逐步模拟每一分钟。 我们可以将当前状态存储在将坐标映射到蚂蚁计数的字典中。 在每次迭代中，我们扫描所有单元格，对于有四只或更多蚂蚁的单元格，我们减去四的倍数并为每个邻居加一。 这种方法是正确的，因为它反映了问题陈述，但最坏的情况是 30,000 只蚂蚁分布在多次迭代中，并且受影响的单元格数量迅速增长。 如果每只蚂蚁可以向多个方向移动，则更新次数很容易超过 10^7，这对于 1 秒的时间限制来说是很慢的。 

关键在于该过程类似于 4 进制“进位”系统。 每个单元只能以四的倍数分布蚂蚁，余数在 0 到 3 之间。由于网格是无限的，我们可以根据其邻居贡献的蚂蚁递归计算任意位置的蚂蚁数量，将分散视为重复除以 4。 这使我们能够通过记忆实现自上而下的递归模拟，而不是模拟每一分钟，从而大大减少了计算量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 对于 n=30,000 来说太慢 |
 | 递归记忆化 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将初始蚂蚁计数存储在原点。 所有其他单元格都以零只蚂蚁开始。 
2. 定义递归函数`ants_at(x, y)`返回单元格中蚂蚁的最终数量`(x, y)`。 如果之前已经计算过该值，则从记忆字典中返回该值。 
3.如果`(x, y)`是原点，考虑那里的蚂蚁总数。 原点处的最终蚂蚁是重复去除四只一组后的剩余蚂蚁，即`n % 4`。 
4. 对于任何其他单元格`(x, y)`，它的最终蚂蚁计数是从它的四个邻居流向它的蚂蚁数量的总和。 每个邻居都可以做出贡献`floor(ants_at(neighbor)/4)`蚂蚁到当前单元格。 
5. 缓存计算值`(x, y)`并归还它。 
6. 通过调用回答每个查询`ants_at(x_i, y_i)`。 

为什么有效：不变的是，在所有可能的四只蚂蚁群体分散之后，每个单元最终都会与剩余的 0-3 只蚂蚁保持稳定。 递归计算考虑了相邻单元的贡献，并且在没有记忆的情况下永远不会重新访问单元。 由于每只蚂蚁只能以四的倍数传播，因此递归深度和总计算量受到蚂蚁总数的限制。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1000000)

def main():
    n, t = map(int, input().split())
    queries = [tuple(map(int, input().split())) for _ in range(t)]
    
    memo = {}
    
    def ants_at(x, y):
        if (x, y) in memo:
            return memo[(x, y)]
        if x == 0 and y == 0:
            memo[(x, y)] = n % 4
            return memo[(x, y)]
        total = 0
        for dx, dy in [(1, 0), (-1, 0), (0, 1), (0, -1)]:
            nx, ny = x - dx, y - dy
            if abs(nx) + abs(ny) > 30000:  # pruning far cells
                continue
            total += ants_at(nx, ny) // 4
        memo[(x, y)] = total
        return total
    
    for x, y in queries:
        print(ants_at(x, y))

if __name__ == "__main__":
    main()
```这`memo`字典防止重新计算。 递归总是在四个方向上偏移坐标，因为单元接收来自邻居的蚂蚁，而不是自身。 修剪是可选的，但可以加快对无法接收蚂蚁的非常远的单元的查询速度。 设置递归限制可以确保我们避免 Python 的默认深度错误。

 ## 边缘情况

 如果 n = 0，则原点永远不会有四只蚂蚁，因此所有查询都返回 0。递归立即停止。 

如果 n = 4，则原点分配所有蚂蚁，留下零，邻居各收到一只。 查询(0,0)返回0，而邻居返回1。 

对于距离较大的查询，例如 x = 10^9，递归会正确返回 0，因为蚁群无法到达如此遥远的单元格：记忆有效地修剪了无法到达的位置。
