 ## 解决方案

 ## 问题理解

 我们被要求建立一个$n \times n$网格仅填充零和一，约束条件是$k$单元格包含 。 网格不是直接根据网格的放置方式来判断的，而是根据它们在行和列上分布的不均匀程度来判断。 

对于每一行，我们计算它包含多少个，生成一系列行总和。 我们对列也做同样的事情。 网格的成本取决于这些总和的分散程度：我们对最大和最小行总和之间的差值进行平方，并为列添加相同的数量。 

所以任务不仅仅是准确放置$k$，但放置它们时应使行总和尽可能平衡，列总和也尽可能平衡。 

约束足够大，任何尝试组合放置的尝试都是不可能的。 即使迭代所有网格也是不可能的，因为可能的网格数量是$2^{n^2}$。 即使评估单个网格也很便宜，但构建最佳网格需要理解结构而不是搜索。 

当出现一个微妙的极端情况时$k = 0$或者$k = n^2$。 在这两种情况下，网格都是完全均匀的，因此每行和每列的总和都是相同的，并且成本为零。 如果不仔细对待这些极端情况，“逐行展开”的天真贪婪方法仍然可能意外地引入不平衡。 

另一个棘手的情况是当$k$不能被整除$n$。 例如，与$n = 4, k = 7$，人们可能会尝试均匀地填充行，但列不平衡成为真正的限制因素，并且粗心的按行填充可能会在列中产生很大的差异，即使行看起来是平衡的。 

## 方法

 蛮力方法会尝试所有可能的位置$k$其中$n^2$位置，计算所有行和列的总和，并评估成本函数。 这是正确的但不可行：选择的数量是$\binom{n^2}{k}$，即使对于中等强度的情况，也会呈指数增长，甚至变得天文数字般大$n$。 

关键的观察结果是，行总和和列总和仅取决于我们沿行和列分布的均匀程度。 如果我们考虑按顺序放置，我们所能希望的最好的结果就是保持行总和最多相差一，列总和也是如此。 任何较大的不平衡都会立即增加平方惩罚，因此最佳配置必须尽可能“平坦”。 

这导致了一个建设性的策略：我们以一种几乎均匀分布在行和列上的方式填充网格。 实现此目的的一种自然方法是按行优先顺序遍历网格并逐个放置。 但是，为了同时确保行和列平衡，我们使用循环对角线图案而不是直线填充。 

具体来说，我们将其放置在位置$(i, (i + j) \bmod n)$，当我们在行中移动时，在列中循环。 这确保每行接收到$\lfloor k/n \rfloor$或者$\lceil k/n \rceil$，对于列也类似。 两个维度上的不平衡同时被最小化。 

一旦我们接受行和列的总和最多相差一，计算最小成本就变得很简单：它只取决于有多少行（或列）获得了额外的一。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(\binom{n^2}{k} \cdot n^2)$|$O(n^2)$| 太慢了 |
 | 最佳施工|$O(n^2)$|$O(n^2)$| 已接受 |

 ## 算法演练

 我们通过尽可能均匀地分布网格来构建网格。 

1. 计算理想情况下每行应该接收多少个。 让$q = k // n$和$r = k \bmod n$。 这意味着每一行都会得到$q$或者$q+1$那些。 这是保持行总和尽可能平衡的唯一可能方法。 
2. 我们将额外的分配给第一个$r$行。 这确保行总和最多相差一，并最小化$\max(R) - \min(R)$。 
3. 在每一行中，我们不是将其任意放置在第一列中，而是循环移动放置。 排$i$将其放入列中$(i \cdot q + j) \bmod n$。 这可以防止列严重偏向早期索引。 
4. 我们对所有行重复此模式，确保列总和也最多相差 1。 循环移位是将行方向的多余部分均匀地分布在列上。 
5. 最后，我们使用已通过构造确定的最大和最小行和列总和来计算成本。 

### 为什么它有效

 关键的不变量是构造后，每行总和是$q$或者$q+1$，并且每列总和也是$\lfloor k/n \rfloor$或者$\lceil k/n \rceil$。 由于没有行或列与平均值的偏差超过 1，因此任何进一步减少一侧方差的尝试都会迫使另一侧变得更加不平衡。 循环移位确保了行和列之间的对称性，因此这两个维度都不受青睐，这正是最小化平方范围之和的原因。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        
        grid = [[0] * n for _ in range(n)]
        
        q, r = divmod(k, n)
        
        # distribute ones row-wise with cyclic shifts
        for i in range(n):
            ones = q + (1 if i < r else 0)
            for j in range(ones):
                col = (i + j) % n
                grid[i][col] = 1
        
        # compute row and column stats
        row = [sum(row) for row in grid]
        col = [sum(grid[i][j] for i in range(n)) for j in range(n)]
        
        cost = (max(row) - min(row)) ** 2 + (max(col) - min(col)) ** 2
        
        print(cost)
        for row in grid:
            print(''.join(map(str, row)))

if __name__ == "__main__":
    solve()
```该构造首先使用商余数分布修复行不平衡。 每行内部的循环移位可防止在连续行的同一列中堆叠行，否则会增大列方差。 

成本计算仅在施工后进行，因为结构保证它已经是最佳的。 

## 工作示例

 ### 示例 1

 输入：```
2 2
```这里$q = 1, r = 0$。 每行恰好有一个 1。 

| 行| 放置的列 | 行总和 |
 | ---| ---| ---|
 | 0 | 0 | 1 |
 | 1 | 1 | 1 |

 | 专栏 | 总和|
 | ---| ---|
 | 0 | 1 |
 | 1 | 1 |

 成本是$(1-1)^2 + (1-1)^2 = 0$。 

这证实了统一行分配已经达到了完美的平衡$k$划分$n$。 

### 示例 2

 输入：```
3 8
```这里$q = 2, r = 2$。 两行有 3 个，一行有 2 个。 

| 行| 放置的（循环）| 行总和 |
 | ---| ---| ---|
 | 0 | 0 1 2 | 0 1 2 3 |
 | 1 | 1 2 0 | 1 2 0 3 |
 | 2 | 2 0 | 2 2 |

 列总和变为：

 | 专栏 | 总和|
 | ---| ---|
 | 0 | 2 |
 | 1 | 2 |
 | 2 | 2 |

 行范围是$3 - 2 = 1$，列范围为$2 - 2 = 0$，所以成本是$1^2 + 0^2 = 1$。 

这显示了即使行不均匀时循环移位如何防止列不平衡。

 ## 边缘情况

 当$k = 0$，该结构产生一个全零网格。 每行和列的总和都为零，因此两个范围都为零，并且成本被正确计算为零。 仍然尝试循环放置的贪婪实现将错误地尝试访问列，并可能引入无效写入，除非明确保护。 

什么时候$k = n^2$，每个单元格都充满了一个。 行和列的总和都是$n$，因此方差再次为零。 该结构自然地处理了这个问题，因为$q = n$和$r = 0$，所以每一行都被填满。 

什么时候$k < n$，只有第一行接收。 循环移位确保这些分布在不同的列上，防止列集中。 如果不进行移位，所有的值都将堆叠在同一列中并产生等于 1 的列范围，与展开配置相比，这将是次优的。
