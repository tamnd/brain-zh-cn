 ## 解决方案
 ## 问题理解

 我们有两种类型的饼干和两种类型的客人。 饼干分为香草饼干和巧克力饼干，客人也分为两种行为类型。 客人按照我们可以选择的顺序到达，每位客人仅根据当前剩余香草饼干和巧克力饼干的数量进行比较来做出决定。 

1 类访客查看当前状态。 如果香草饼干严格来说比巧克力饼干更重要，那么他们会选择香草饼干； 否则他们会选择巧克力。 第二类客人在相同的比较下会做出相反的偏好。 选择一种口味后，客人会吃一块该口味的饼干（如果有的话），否则该订购过程将立即失败。 

任务是确定是否存在所有客人的任何排列，以便每个客人都能成功吃到一块饼干。 

限制非常大：cookie 数量和访客数量最多可达 10^18。 这立即排除了对来宾的任何模拟或任何依赖于具有分支决策的单个来宾的线性处理的状态扩展。 任何有效的解决方案都必须将问题减少到每个测试用例的算术检查数量恒定。 

当其中一种 cookie 类型从零开始时，就会出现一个微妙的问题。 例如，如果没有巧克力饼干，但至少一位客人可能在某个时候选择巧克力，那么订购必须确保这种情况永远不会发生。 同样，如果两种类型在某个时刻相等，则打破平局的行为变得确定性，但仍然可以翻转后续客人的结果。 

主要困难在于系统不仅由计数驱动，还由差值 v − c 的符号驱动，这决定了所有决策。 这意味着整个过程取决于我们是否处于“香草主导”或“巧克力主导”状态。 

一种简单的方法可能会尝试模拟客人类型的所有排列或贪婪地选择下一位客人。 这会失败，因为排列的数量是 n + m 的阶乘，而且即使是贪婪的模拟也可能会失败，因为局部选择会影响 v − c 中未来的符号变化。 

## 方法

 暴力方法将枚举 n + m 个客人的所有排列并模拟每个排序。 对于每个客人序列，我们跟踪（v，c）并逐步应用规则，检查是否有客人生气。 这是正确的，因为它直接反映了该过程。 然而，排列的数量是 (n + m)！，即使对于非常小的输入也是不可能的，并且每次模拟的成本为 O(n + m)，使得总数完全不可行。 

关键的见解是系统的行为仅取决于香草饼干和巧克力饼干之间的差异，而不取决于它们的绝对值。 每位客人要么将香草味或巧克力味减少一倍，他们的选择由 v − c 的符号决定。 

因此，我们不是根据确切的顺序来思考，而是根据我们可以安全地应用每种“类型效应”多少次来进行推理，同时保持系统的一致性。 

让我们定义差值 d = v − c。 1 类客人从较大的一堆中消耗，推动系统走向平衡，而 2 类客人则将其推向相反的方向。 重要的观察结果是，每种客人类型都试图使系统朝着他们的首选选择仍然可用的方向稳定。 

这将问题转化为检查我们是否可以按顺序分配客人，以防止任一 cookie 类型在满足相应需求之前耗尽。 正确的条件最终仅取决于当一侧与另一侧相比太小时我们是否可以避免强制符号矛盾。

表达这一点的一种简洁方式是：当且仅当双方都没有被迫提供比其初始可用性允许的更多的“相反选择需求”时，系统才是可行的，这导致了一个基于将 n 和 m 与 a 和 b 的移位版本进行比较的简单条件。 

我们将问题简化为检查在考虑来宾类型之间的强制不平衡后是否可以支持较小的资源。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（排列）| O((n+m)！·(n+m)) | O(n+m) | 太慢了|
 | 贪婪不变约简| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 关键是将动态过程转化为基于不平衡性的可行性检验。 

## 第 1 步：将问题标准化

 我们对称地对待香草和巧克力。 我们假设我们分析哪一方实际上更强，以及是否可以安排客人以避免发生强制错配。 

其核心思想是，只有相对优势才重要，而不是确切的顺序。 

## 第二步：观察强制消费结构

 根据类型，每位客人要么从当前较大的一堆中消费，要么从较小的一堆中消费。 这意味着客人有效地“推动”系统趋向或远离平衡。 

如果与相反类型的可用 cookie 相比，存在太多一种类型的访客，我们最终将被迫进入所需 cookie 类型不可用的状态。 

## 步骤 3：减少不平衡的可行性

 一旦我们考虑了方向压力，我们就会检查配置是否可以维持所有客人的需求，确保任何一方相对于供应都不会出现过度需求。 

这导致检查访客类型之间的差异是否与初始 cookie 差异兼容，以防止崩溃。 

具体来说，如果客人类型之间的绝对不平衡不超过初始cookie吸收定向压力的能力，则该系统是可行的。 

## 第四步：最终决定

 计算通过比较得出的必要平衡条件：

 - 存在多少类型 1 和类型 2 客人
 - 香草饼干和巧克力饼干之间存在多少初始剩余

 如果可以对系统进行排序，以便控制永远不会陷入死胡同，则打印“是”，否则打印“否”。 

### 为什么它有效

 该过程完全由 v − c 的符号控制。 每个客人的决定仅取决于我们目前这种差异是否处于正、负或零状态。 这意味着整个序列可以被视为控制整数上的行走，其中每一步消耗一侧的一个单位并可能翻转符号。 

唯一失败的方法是在客人请求时被迫进入所需 cookie 类型为空的状态。 由于我们可以任意重新排序客人，唯一真正的限制是是否存在一种调度，可以防止较弱的一方过早耗尽，同时仍然允许足够的转换来满足相反的需求。 

这减少了客人数量和初始 cookie 不对称性之间的平衡条件，这就是为什么恒定时间检查就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b, n, m = map(int, input().split())

        # Symmetry: ensure a >= b by swapping if needed
        if a < b:
            a, b = b, a
            n, m = m, n

        # Now a is the larger or equal pile
        # We check feasibility based on whether the smaller pile can support demand
        # derived from imbalance between guest types
        if m <= b:
            print("Yes")
        else:
            print("No")

if __name__ == "__main__":
    solve()
```该实现使用对称性来减少状态空间。 我们交换 cookie 类型，以便我们始终从香草 (a) 至少与巧克力 (b) 一样大的角度进行推理。 这使我们能够一致地解释类型对齐。 

然后，决策检查的重点是“需求相反”的客人是否超出了较小堆的容量。 如果他们不这样做，我们总是可以让客人交错，以便消费保持有效。 否则，我们将不可避免地达到所需 cookie 类型耗尽的状态。 

关键的微妙之处是确保交换包括 cookie 计数和客人计数。 忘记交换 n 和 m 会破坏对称性论证并导致不正确的可行性检查。

 ## 边缘情况

 一种重要的边缘情况是，当两个 cookie 数量相等且客人严重偏差时。 例如，如果a = b但m很大，则交换不会改变任何内容，条件直接检查m是否可以被b吸收。 由于在这种情况下 b 等于 a，可行性完全取决于条件正确捕获的对称容量是否成立。 

另一种边缘情况是一种 cookie 类型最初为零。 如果 a = 0 且 b > 0，交换可确保我们始终从较大的一侧进行分析，从而防止误报，否则算法会尝试将客人分配到不存在的堆中。 

当 n 和 m 非常大（最多 10^18）时，会出现第三种边缘情况。 该算法从不迭代，因此它仅使用比较和交换来安全地处理这些值，完全避免溢出，因为 Python 整数是无界的。
