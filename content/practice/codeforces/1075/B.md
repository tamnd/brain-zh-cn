 ## 解决方案
 ## 问题理解

 我们有一组人位于数轴上。 每个人要么是骑手，要么是出租车司机，所有职位都是不同的，并且已经按升序排列。 

当乘客叫车时，系统总是根据线路上的绝对距离将请求分配给最近的出租车司机。 如果两个出租车司机距离相等，则选择坐标较小的司机。 每个乘客都独立地生成一个请求，我们想知道如果每个人同时叫出租车，将会为每个出租车司机分配多少乘客。 

任务是计算，对于每个出租车司机，按照司机之间协调性增加的顺序，在这种最接近的平局打破规则下，有多少乘客将与该司机匹配。 

输入规模达到总人数达20万人。 这立即排除了任何将每个乘客与所有出租车司机单独进行比较的解决方案，因为在最坏的情况下这将是二次的并且远远超出时间限制。 解必须接近线性或线性算数。 

当多个乘客恰好位于两个相邻出租车司机之间的中点时，就会出现微妙的边缘情况。 在这种情况下，打破平局总是将任务分配给左边的出租车司机。 例如，如果驾驶员位于 2 和 6，骑手位于 4，则骑手将转到 2。任何解决方案都必须尊重这种确定性边界行为。 

另一个极端情况是所有驾驶员都位于骑手集群的一侧。 例如，如果所有出租车都在右侧，则每个乘客都会被分配到最左边的出租车，因为它是最近的可用出租车。 

## 方法

 解决这个问题的一个直接方法是独立处理每个乘客，扫描所有出租车司机以找到最近的出租车司机。 对于每个骑手，我们计算到所有 m 个驾驶员的距离并选择最小值。 这是正确的，因为它直接遵循问题定义。 

然而，这种方法需要 O(nm) 运算。 当 n 和 m 达到 100,000 时，这将变成最多 10^10 次比较，这是不可行的。 

关键的观察结果是，乘客和出租车司机都位于一条排序线上，距离比较仅取决于相对顺序。 对于任何固定的乘客来说，只有左边最近的出租车司机和右边最近的出租车司机可能是最佳的。 所有其他司机都离得更远。 

这减少了为每个乘客维护每侧最近的出租车司机的问题。 如果我们在跟踪驾驶员位置的同时对线路进行排序或扫描，我们可以在预处理后的 O(1) 摊销时间内分配每个乘客。 实现此目的的标准方法是从左到右扫过线路，同时保留最后看到的出租车司机，并预先计算右侧的下一个出租车司机。 已知这两个邻居后，我们可以比较距离并使用坐标顺序解决关系。 

这将问题转化为线性扫描，每个骑手做出恒定时间的决策。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了|
 | 与最近邻居的最佳扫描| O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 我们首先将位置分成两个列表：一个包含所有出租车司机坐标，另一个包含所有乘客坐标。 由于原始序列已经按坐标排序，因此我们可以一次性构建这些列表。 

接下来，我们准备一个从每个出租车司机坐标到其在司机排序列表中的索引的映射。 这是必需的，因为输出必须按驱动程序坐标排序，而不是按输入顺序排序。

然后，我们针对线路上的每个位置计算左侧最近的出租车司机。 我们从左向右扫视，记住我们最后见到的出租车司机。 每当我们遇到出租车司机时，我们都会更新这个值。 对于位置 x 的骑手，这为我们提供了左侧最接近的候选者。 

我们还通过以相同的方式从右向左扫描来计算右侧最近的出租车司机。 

现在每个乘客最多有两个候选人：左边的出租车司机和右边的出租车司机。 我们比较他们与骑手的距离。 如果距离较近，我们会将乘客分配给该司机。 如果两者同样接近，我们将其分配给左边的，因为它的坐标更小。 

最后，我们增加所选出租车司机的计数器，并按司机坐标的递增顺序输出所有计数。 

### 为什么它有效

 乘客的分配仅取决于最近的出租车司机。 在一条线上，任何点在集合中都有一个唯一的最近元素，并且该最近元素必须按排序顺序紧邻左侧或紧邻右侧。 所有其他候选者都严格地比这两个候选者中的至少一个更远。 平局规则与等距离情况下总是优先选择左侧是一致的，因此这两个候选者之间的比较完全决定了结果。 

这表明将搜索空间减少到每个骑手两个候选人可以保持每个任务的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
x = list(map(int, input().split()))
t = list(map(int, input().split()))

riders = []
drivers = []

for i in range(n + m):
    if t[i] == 1:
        drivers.append(x[i])
    else:
        riders.append(x[i])

drivers.sort()

# maps driver position to its index in output order
pos_to_idx = {drivers[i]: i for i in range(m)}

INF = 10**18

left_driver = [-1] * (n + m)
right_driver = [-1] * (n + m)

last = -1
for i in range(n + m):
    if t[i] == 1:
        last = x[i]
    else:
        left_driver[i] = last

last = -1
for i in range(n + m - 1, -1, -1):
    if t[i] == 1:
        last = x[i]
    else:
        right_driver[i] = last

ans = [0] * m

for i in range(n + m):
    if t[i] == 0:
        x0 = x[i]

        L = left_driver[i]
        R = right_driver[i]

        # both exist
        if L != -1 and R != -1:
            dL = x0 - L
            dR = R - x0

            if dL <= dR:
                ans[pos_to_idx[L]] += 1
            else:
                ans[pos_to_idx[R]] += 1

        elif L != -1:
            ans[pos_to_idx[L]] += 1
        else:
            ans[pos_to_idx[R]] += 1

print(*ans)
```该实现依赖于两个方向扫描。 第一次扫描记录了每个乘客位置最靠近其左侧的出租车司机。 第二次扫描对右侧执行相同的操作。 最后的循环通过比较最多两个候选者来独立地解决每个骑手的问题，确保每个人的处理时间恒定。 

关键细节是决胜条件`dL <= dR`，这确保了当乘客恰好位于中间时，由于坐标较小，优先权会转向左侧的出租车司机。 

字典`pos_to_idx`将驱动程序坐标转换为输出索引，以便结果可以按所需顺序累积。

 | 空间| O(n + m) | 数组存储每个位置的左右最近的驱动程序 |

 该解决方案在限制范围内运行舒适，因为它仅对每个输入元素执行恒定量的工作，并且没有对乘客和驾驶员的嵌套迭代。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    x = list(map(int, input().split()))
    t = list(map(int, input().split()))

    drivers = []
    riders = []
    for i in range(n + m):
        if t[i] == 1:
            drivers.append(x[i])
        else:
            riders.append(x[i])

    drivers.sort()
    pos_to_idx = {drivers[i]: i for i in range(m)}

    left_driver = [-1] * (n + m)
    right_driver = [-1] * (n + m)

    last = -1
    for i in range(n + m):
        if t[i] == 1:
            last = x[i]
        else:
            left_driver[i] = last

    last = -1
    for i in range(n + m - 1, -1, -1):
        if t[i] == 1:
            last = x[i]
        else:
            right_driver[i] = last

    ans = [0] * m

    for i in range(n + m):
        if t[i] == 0:
            x0 = x[i]
            L = left_driver[i]
            R = right_driver[i]

            if L != -1 and R != -1:
                if x0 - L <= R - x0:
                    ans[pos_to_idx[L]] += 1
                else:
                    ans[pos_to_idx[R]] += 1
            elif L != -1:
                ans[pos_to_idx[L]] += 1
            else:
                ans[pos_to_idx[R]] += 1

    return " ".join(map(str, ans))

# all drivers, symmetric

 ## 边缘情况

 一种极端情况是只有一名出租车司机。 扫描仍然将左侧和右侧的候选人指定为缺席一侧，因此每个车手都会回落到该单一车手。 该算法正确地增加了所有骑手的唯一计数器。 

另一个边缘情况是，所有乘客都位于两个出租车司机之间，距离两侧相等。 条件`dL <= dR`确保对左侧驾驶员的确定性分配。 抽签保证了两位候选人都被正确识别，因此每个骑手都会进行一次平局决胜。 

当乘客出现在第一个出租车司机之前或最后一个出租车司机之后时，就会出现最后一个边缘情况。 在这两种情况下，仅存在两个候选方向之一，并且算法将所有此类乘客安全地分配给唯一可用的邻居，而不会尝试无效的比较。
