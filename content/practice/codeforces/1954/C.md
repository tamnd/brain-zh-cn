 ## 解决方案
 ## 问题理解

 我们有两个非常大的整数表示为字符串，它们都有相同的位数。 每个数字都在 1 到 9 之间，因此没有零会使位置效应或前导零问题变得复杂。 

唯一允许的操作是交换两个数字之间相同位置的数字。 换句话说，对于任何索引 i，我们可以保留该对`(x[i], y[i])`照原样，或者交换它们，使它们变成`(y[i], x[i])`。 这个决定对于每个位置都是独立的，但目标是全局的：我们希望两个数字的最终数值能够最大化乘积`x * y`。 

重要的观察结果是，每个位置的贡献不同，具体取决于数字是放置在较高编号的字符串还是较低编号的字符串中。 由于乘法对位置表示法中的数字位置很敏感，因此前面的（更重要的）数字比后面的数字更重要。 然而，我们构建的不是单个数字，而是两个数字，其乘积同时取决于两个数字。 

这些约束允许最多 1000 个测试用例和最多 100 位数字。 这立即表明每个测试用例需要 O(n) 或 O(n log n) 解决方案，因为任何数字上的二次或指数方法都太慢。 

一个天真的错误是假设我们应该总是按字典顺序最大化每个单独的数字。 但这会失败，因为提高一个数字可能会严重损害另一个数字。 

例如，假设在某个位置我们有数字`(9, 1)`。 将它们保留为`(9, 1)`使`x`局部较大但`y`较小。 交换给出`(1, 9)`。 就本地而言，如果孤立地考虑，这两个决定显然都不是更好，但产品取决于两者。 这表明决策必须是对称的且经过仔细选择。 

另一个失败案例来自于每个数字的贪婪独立数字最大化：如果我们总是将较大的数字放入`x`，我们可能会不小心将大数字聚集到一个数字中，并过多削弱另一个数字，从而减少乘积。 

核心困难是根据每个位置决定货币对的哪种排列会产生最佳的全局乘法效应。 

## 方法

 暴力方法会尝试所有`2^n`交换位置的方式。 对于每种配置，我们计算所得的两个数字并将它们相乘。 这是正确的，因为它探索了每个数字对的每种可能的分配。 然而，当 n 达到 100 时，这会导致`2^100`每个测试用例的可能性，这是完全不可行的。 

关键的见解来自于注意到乘法奖励平衡而不是集中。 如果我们按数字扩展乘积，交换一对`(a, b)`仅影响两个数字中的一位数字位置，并且其对最终产品的影响仅取决于相对于其他位置的本地选择。 更准确地说，每个位置根据数字在两个数字之间的分布方式贡献一个术语，并且交换仅在本地改变该贡献。 

如果我们独立考虑单个位置，只有两个选择：保留`(x[i], y[i])`或将其交换为`(y[i], x[i])`。 我们不需要考虑位置之间的相互作用，因为任何全局分配只是这些独立二元选择的组合。 当每个本地决策以平衡的方式增加较大数字对两个数字的贡献时，乘积最大化。 

这导致了一个令人惊讶的简单规则：在每个位置，我们应该确保将较大的数字分配给当前在该位置具有较小数字的数字，但由于数字在各个位置之间是独立的，并且在这个推理级别的乘法中没有进位交互，因此最佳策略简化为一致的贪婪平局打破：我们保持对的排序，以便第一个数字在字典顺序上不小于第二个数字，从而保留最大数字配对对称性。 

标准推导进一步简化：最大化`x * y`，我们希望两个数字在最显着的不同位置上尽可能大，并且交换只有在改善两个数字之间大数字的平衡时才有用。 最佳策略是使两个数字尽可能“对齐”，这是通过确保在每个位置我们将较大的数字一致地分配给相同的数字来实现的（例如，始终将较大的数字推到同一侧或遵循基于一阶差分奇偶校验的一致规则）。 这种贪婪的局部对齐使乘积最大化，因为任何不匹配都会减少一个因素，而不会以更高的显着性补偿另一个因素的增益。 

一个干净的实现是对每个数字对进行排序，这样我们总是将较大的数字分配给`x`并且更小到`y`反之亦然，并根据全局一致性选择方向，以保持最大产品。 

事实上，最简单的最佳观察是：我们应该确保对于每个位置，我们分配数字，使得结果数字尽可能接近，同时保持很大，这是通过以最小化不平衡的方式对每个位置的数字进行排序来实现的。 这种贪婪的局部配对是最优的，因为除了位置大小之外不存在任何交叉位置依赖性。

 ## 算法演练

 1. 读取代表数字的两个字符串。 

我们将它们视为数字数组，以便我们可以独立处理每个位置。 
2. 对于从左到右的每个索引 i，考虑该对`(a, b) = (x[i], y[i])`。 

在这个位置上，我们决定交换是否会改善全局产品。 
3. 比较两种可能的分配：保留`(a, b)`或交换到`(b, a)`。 

我们选择的分配尽可能使第一个数字不小于第二个数字，因为较大的前导数字在乘积中占主导地位。 
4. 相应地构造结果字符串。 

每个位置都是独立决定的，但保持一致，确保我们不会在两个数字之间引入不必要的不​​对称。 
5. 输出最后两个数字。 

### 为什么它有效

 每个数字位置通过位置权重成倍地贡献。 由于所有数字均为正数，并且头寸之间不存在进位交互，因此一个指数的交换不会影响其他指数决策的相对顺序。 这将问题简化为为每个位置选择一种排列，以最大化较高数字对产品产生更重大影响的贡献。 贪婪对齐确保任何本地交换都不能在不减少其他更重要位置的乘积的情况下增加乘积，从而保证全局最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x = list(input().strip())
        y = list(input().strip())

        a = []
        b = []

        for i in range(len(x)):
            if x[i] < y[i]:
                x[i], y[i] = y[i], x[i]
            a.append(x[i])
            b.append(y[i])

        print("".join(a))
        print("".join(b))

if __name__ == "__main__":
    solve()
```实现独立地处理每个测试用例。 对于每个位置，它强制执行一致的排序：较大的数字进入`x`，较小的变为`y`。 这是通过在需要时进行交换来实现的。 

我们使用字符列表是因为 Python 中的字符串是不可变的，重复连接效率很低。 最终的连接有效地重建了输出。 

决策规则是局部的，但正确性依赖于每个数字位置在允许的转换方面独立贡献的事实。

 ## 边缘情况

 一种边缘情况是每个位置的所有数字都相同，例如`111...`和`111...`。 在这种情况下，交换在任何位置都不会改变任何内容，因此任何输出都是有效的。 该算法永远不会交换，因为`x[i] < y[i]`对于相等性来说是假的，保持正确性。 

另一种边缘情况是，一个数字在数字方面严格较小，但在后面的位置具有较大的数字。 例如，`x = 219`,`y = 981`。 该算法在需要的每个位置进行交换并产生`921`和`189`。 每次交换都是局部最优的，最终的安排确保较大的数字始终分配给同一侧，避免不必要的不​​平衡，从而减少乘积。
