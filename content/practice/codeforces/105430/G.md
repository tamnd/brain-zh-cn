 ## 解决方案
 ## 问题理解

 我们给出了一组$n$隐藏的物品，称为娃娃。 正是有一个娃娃是特别的并且行为不同：每当它与任何其他娃娃进行比较时，结果总是平局。 其余$n-1$每个娃娃都属于三个类别之一，这些类别形成循环支配关系：快乐击败愤怒，愤怒击败悲伤，悲伤击败快乐。 

我们不知道哪个洋娃娃是哪个。 相反，我们可以询问“Does doll$i$打娃娃$j$？” 并收到二进制答案。 仅当满足以下条件时，响应才是肯定的：$i$严格按规则取胜； 平局和损失均返回零。 

任务是找出最多使用的特殊无情感娃娃的索引$3n$这样的比较。 

约束条件$n \le 20000$意味着任何解决方案在查询数量上都必须是线性或接近线性的。 比较每对娃娃的二次方法需要大约$n^2$查询，这是完全不可行的。 甚至$O(n \log n)$解决方案是可以接受的，但任何比线性查询复杂性更糟糕的解决方案都有可能达到交互限制。 

一个微妙的困难来自于查询响应中的“0”是不明确的。 这可能意味着平局或失败。 这使得在没有仔细结构的情况下，不可能通过简单地根据固定参考来计算输赢来直接识别特殊娃娃。 

一个天真的错误是假设传递性。 例如，如果 A 击败 B，B 击败 C，人们可能会错误地推断出 A 和 C 的某些信息，但情绪的循环性质完全打破了这一点。 

另一个常见的失败是试图通过多数票获胜来选出候选人。 由于每个非特殊娃娃根据对手类型而具有对称行为，因此原始获胜计数并不是特殊娃娃的稳定指标。 

## 方法

 一个蛮力的想法是将每个娃娃与固定枢轴进行比较，并尝试根据其他娃娃的反应对它们进行分类。 然而，由于两个完全不同的原因，比较可能返回零，因此这并不能可靠地区分无情感的娃娃和普通娃娃。 解决这种歧义需要以结构化的方式对娃娃进行比较。 

关键的观察结果是，在任何三个非特殊娃娃中，根据循环规则，至少有一次比较必须产生严格的胜利，而特殊娃娃是唯一一个永远不会产生在交互中一致的胜利或失败结果的玩偶。 特别是，没有感情的娃娃的表现就像一个通用的决胜局：它永远不会击败任何人。 

这表明了一种锦标赛式的淘汰策略。 我们保留了特殊娃娃的当前候选者。 我们对每个新娃娃进行测试。 如果候选人打败了某人，那么这个人偶就不可能是特殊的娃娃，必须更换。 否则，我们保留它。 这是有效的，因为真正的特殊娃娃永远不会产生获胜的反应，因此它永远不会被错误地消除。 

其高效的原因是每个玩偶仅参与恒定数量的查询，从而给出线性的总查询计数。

 ## 算法演练

 我们模拟一个交互式消除过程。 

1. 首先假设娃娃 1 是没有感情的候选者。 这是任意的，因为最初没有可用的信息。 
2. 将娃娃从 2 迭代到$n$，比较当前候选者$c$每个新娃娃$i$。 
3.询问是否$c$节拍$i$。 如果答案是1，那么$c$绝对不是没有感情的，因为没有感情的娃娃永远不会赢得任何战斗。 将候选人替换为$i$， 自从$i$可能仍然是特别的。 
4. 如果答案为 0，则$c$失去或联系$i$。 无论哪种情况，$c$仍然是有效的候选者，因此我们保持不变。 
5.处理完所有娃娃后，输出最终候选。 

更换步骤背后的原因至关重要。 淘汰候选人的唯一方法是证明它的行为就像一个普通的玩偶（它至少获胜一次）。 特殊的娃娃永远不会触发这种情况，因此它在每次出现的比较中都能幸存下来。 

### 为什么它有效

 该过程保持一个不变量：处理完第一个$k$娃娃，现在的候选人肯定是其中没有感情的娃娃$k$如果该前缀中存在这样的娃娃。 每当候选人失去有效性时，它就会被一个尚未因任何获胜证据而被取消资格的玩偶所取代。 由于真正的无情感娃娃在任何比较中都不会产生获胜的反应，因此它永远不会被淘汰。 通过归纳法对所有$n$娃娃们，最后的候选者一定是特别的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(i, j):
    print(f"? {i} {j}")
    sys.stdout.flush()
    return int(input().strip())

def solve():
    n = int(input().strip())

    candidate = 1

    for i in range(2, n + 1):
        res = ask(candidate, i)
        if res == 1:
            candidate = i

    print(f"! {candidate}")
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```该解决方案是围绕单个候选指针构建的，只有当证据证明它不可能是特殊娃娃时，该指针才会更新。 这`ask`函数包装了交互逻辑，确保立即刷新每个查询，这在交互问题中至关重要。 

该循环是严格顺序的，保证每个娃娃最多与当前候选对象进行比较一次。 这避免了任何冗余交互并使查询总数保持线性。 

一个常见的实现错误是忘记在每次查询后刷新输出。 在交互式问题中，即使逻辑正确，刷新失败也会使程序显得空闲并导致运行时失败。

 ## 边缘情况

 当第一个娃娃已经是没有感情的娃娃时，就会出现最小的边缘情况。 在这种情况下，(1, i) 形式的每个查询都会返回 0，因为平局永远不会算作获胜。 该算法永远不会替换候选者，因此它正确地输出 1。 

另一种极端情况是特殊娃娃是最后一个。 每次较早的比较都可能消除由于循环获胜而错误地显得占主导地位的候选者，但最终迭代不可避免地会提升最后剩余的有效候选者。 由于特殊的娃娃永远不会触发对任何人的获胜反应，因此它在过程中永远不会被丢弃，并且会存活到最后。
