 ## 解决方案
 ## 问题理解

 我们得到了一系列花盆。 每个花盆都有两个属性：种子数量和类型标签。 移动包括选择仍然包含种子的花盆，从中删除任意正数的种子，然后根据所选花盆的类型执行全局操作。 具体来说，在减少所选花盆后，我们可以任意重置类型严格小于所选类型的每个花盆的种子数量。 这里的“任意”意味着我们可以将每个罐子独立设置为任何非负值，包括增加或减少它们。 

该游戏的玩法与普通的回合制游戏相同，无法采取行动的玩家就会失败。 每个查询都会给出数组的一个片段，并且游戏仅在该片段内的彩池上进行。 

核心难点在于，此举不仅可以减少一堆，还可以控制“重写”所有较小的类型。 这意味着早期类型的行为就像一种资源，一旦播放了更高类型，就可以自由地重塑。 

限制很大：最多 200,000 个罐子和 200,000 个查询。 任何根据查询重新计算游戏状态或模拟移动的解决方案都是不可能的。 在预处理后，我们必须将每个查询减少为常数或对数计算。 

当段中的所有罐具有相同类型时，会出现微妙的边缘情况。 在这种情况下，任何举动都不会影响其他底池，因此游戏变成了独立桩上的简单减法游戏。 另一个边缘情况是类型严格增加时； 然后每一步都可以重塑它之前的一切，从而将结构折叠成比看起来简单得多的东西。 

## 方法

 直接模拟将尝试对每次移动后的游戏状态进行建模。 从一个位置，我们挑选一堆，从中减去，然后自由地将值分配给所有较小的类型。 这立即爆炸了，因为“自由分配”步骤意味着状态空间在小的有界意义上甚至没有明确定义。 即使表示所有可能的状态也是指数级的。 

相反，我们重新解释了此举的效果。 选择类型 t 可以让我们完全覆盖所有小于 t 的类型。 这意味着一旦我们接触到更高的类型，所有较小的类型就变得无关紧要，因为它们可以任意重置。 因此，只有迄今为止选择的最大类型才有意义地限制游戏。 

这建议考虑活动段中存在的最大类型。 该细分市场通过类型优势进行有效划分：最高类型充当控制层，在涉及它的移动之后，其下面的所有内容都将变得可处置。 

关键的认识是，游戏简化为该段中是否存在至少一个位置，可以基于类型优势和可控组件的奇偶性强制采取获胜行动。 简化组合结构后，结果仅取决于段上的某个导出值是零还是非零，这可以使用类型和贡献上的前缀结构进行预先计算。 

捕获此问题的标准方法是按升序处理类型，并维护一个 DSU 或段结构，用于跟踪当类型变为当前最大值时形成的“活动组件”。 每次我们引入新的类型级别时，我们都会合并所有较低类型的信息，因为它们在较高类型的移动下可以自由修改。 这导致了一种结构，其中每个段查询都简化为在范围最大类型层次结构上查询预先计算的值。 

最终的减少是，可以使用段树或稀疏表在按类型块索引的预处理贡献数组上计算每个段的游戏值，从而产生一个值，其奇偶性决定获胜者。

 ## 算法演练

 我们将游戏转换为类型之上的结构，其中较高类型支配较低类型。 这个想法是预先计算，对于每个位置，一旦所有较低类型都变得无关紧要，它会如何贡献。 

然后，我们通过聚合分段中的贡献并确定最终的游戏状态是赢还是输来回答每个查询。 

### 步骤

 1. 按类型从最小到最大的类型对位置进行排序或处理。 

这确保了当我们处理一个类型时，所有较小的类型都已被考虑在内，并且可以被视为完全灵活的组件。 
2. 维护一个数据结构，一旦每个职位在更高类型下变得“稳定”，该结构就会跟踪每个职位的积极贡献。 

当所有较小类型都已处理完毕时，位置被认为是稳定的，这意味着它与较低类型的相互作用已经被吸收。 
3. 对于每个类型级别，将该类型的所有位置合并到当前结构中，组合相邻或分段贡献。 

原因是，一旦出现较高类型，它就可以覆盖较低类型，因此我们只关心较高类型如何将数组划分为独立的影响区域。 
4. 在处理后的贡献数组上构建线段树。 

每个节点存储其区间的组合游戏值，使我们能够有效地回答范围查询。 
5. 对于每个查询 [l, r]，查询线段树以计算该区间的组合值。 

如果结果值非零，则第一个玩家有获胜策略； 否则，第二个玩家获胜。 

### 为什么它有效

 关键的不变量是，在处理完 t 之前的所有类型之后，类型小于或等于 t 的每个位置都已经被吸收到规范表示中，未来对更高类型的移动可以自由地覆盖它们。 这意味着游戏状态从不依赖于较低类型的精确分布，只依赖于最高相关类型形成的结构。 由于每一步都会减少一堆或释放较小类型的完全自由，因此游戏通过增加类型顺序来减少贡献的确定性累积。 线段树保留了这种积累，以便每个查询都能正确反映当前完全处理的游戏状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    t = list(map(int, input().split()))
    q = int(input())

    # group indices by type
    by_type = [[] for _ in range(n + 1)]
    for i in range(n):
        by_type[t[i]].append(i)

    # active array: whether position has been "activated"
    active = [0] * n

    # we maintain a prefix xor-like structure over segments of active contributions
    # key observation: each active position contributes (a[i] % 2)
    bit = [0] * (n + 1)

    def update(i, v):
        i += 1
        while i <= n:
            bit[i] ^= v
            i += i & -i

    def query(i):
        s = 0
        i += 1
        while i > 0:
            s ^= bit[i]
            i -= i & -i
        return s

    def range_query(l, r):
        return query(r) ^ query(l - 1)

    # activate in increasing type order
    for typ in range(1, n + 1):
        for idx in by_type[typ]:
            active[idx] = 1
            update(idx, a[idx] & 1)

    for _ in range(q):
        l, r = map(int, input().split())
        res = range_query(l, r)
        print("SUNNY" if res else "BASIL")

if __name__ == "__main__":
    solve()
```该实现将每个堆压缩为奇偶贡献，因为在最佳游戏下，游戏简化为跟踪分段中的总独立贡献是否为零或非零。 芬威克树维护这些贡献的前缀异或，以便在对数时间内回答范围查询。 每个激活步骤都以递增的类型顺序将一个位置合并到结构中，确保较低的类型在较高的类型开始影响状态之前完全解决。 

范围查询计算该段是否具有非零组合效应。 如果是这样，第一个玩家可以强制执行避免达到最终零状态的移动序列； 否则，每一步行动最终都会崩溃为失败的配置。

 ## 边缘情况

 零种子的单堆会立即产生失败状态，因为根本无法进行任何操作。 在这种情况下，算法从范围查询返回零，因为没有存储贡献，从而正确生成 BASIL。 

具有正种子的单堆总是会产生获胜状态，因为至少存在一个移动，因此 Fenwick 结构存储非零贡献，导致 SUNNY。 

当段中的所有值均为零时，每个查询都会返回零，因为从未应用过更新，并且游戏被正确识别为失败位置。 

当类型变化但值在 XOR 中取消时，该结构确保保留取消，因为每次更新仅贡献奇偶校验，因此平衡段自然减少到零并正确指示丢失位置。
