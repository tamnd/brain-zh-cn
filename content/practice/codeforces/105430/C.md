 ## 解决方案
 ## 问题理解

 我们得到一个正整数数组，每个连续子数组根据两个因素贡献一个值：该子数组中所有元素的最小公倍数及其端点索引的乘积。 任务不是计算单个全局值，而是回答许多查询，每个查询将我们限制在一个子数组区间内。 对于每个查询间隔$[l, r]$，我们必须考虑其中的每个子子数组，计算其 LCM，将其乘以其索引端点，并对所有内容求和。 

所以每个查询都要求求总和$[L, R]$完全包含在$[l, r]$，其中分段的贡献是$\text{LCM}(a_L, \dots, a_R) \cdot L \cdot R$，对一个大素数取模。 

结构致密。 对于每个查询，我们都会总结$\Theta((r-l+1)^2)$子数组，每个子数组都涉及对可能很长的段的 LCM 计算。 和$n, Q \le 10^5$，任何重新计算每个段或每个查询的 LCM 的方法都会立即变得太慢。 

LCM 行为会立即出现一些微妙的边缘情况。 首先，即使子阵列中的微小变化也可以极大地增加 LCM。 例如，在$[2, 3, 4]$，当扩展段时，LCM 从 2 跳到 12，因此朴素前缀聚合的行为不是线性的。 其次，重复值并不能以直接的方式简化问题，因为 LCM 对最大质数指数而不是等式模式敏感。 第三，答案取决于索引乘法$L \cdot R$，这意味着我们无法在不跟踪位置的情况下预先计算纯粹基于价值的贡献。 

## 方法

 蛮力方法遵循字面定义。 对于每个查询，枚举所有子数组$[L, R]$，通过迭代其元素来计算段的 LCM，乘以$L \cdot R$，并积累。 即使 LCM 从先前的端点开始增量维护，由于 gcd 操作，每个扩展至少花费对数因子，使得每个查询大致$O((r-l)^2 \cdot \text{cost of LCM update})$。 在最坏的情况下，这会变成$O(n^3)$，这是远远超出可接受范围的。 

关键的观察结果是，LCM 以一种非常结构化的方式是单调的：当我们向右扩展一段时，LCM 要么保持不变，要么通过合并更高的素数幂而增加。 仅当新元素提供当前 LCM 中尚不存在的主要功率时，每个扩展才能更改 LCM。 

这表明了一个经典的离线转换：我们不是为每个子数组重新计算 LCM，而是为每个起始索引维护$L$当我们扩展时当前 LCM 的值$R$，但我们压缩更新，以便每个不同的 LCM 值与最大间隔相关联$R$。 这将问题转化为在 LCM 恒定的范围内汇总贡献。 

为了有效地管理范围查询，我们使用扫描右端点来预先计算所有子数组的贡献。 对于每个$R$，我们维护以结尾的子数组的所有不同的 LCM 值$R$，按起始位置分组。 由于 LCM 仅当素数指数最大值变化时才会变化，因此我们可以为每个元素维护一个“断点”结构$R$，类似于维护贡献域递减的段堆栈。 

然后，我们将贡献累积到一个全局结构中，索引为$(L, R)$，但由 LCM 加权。 由于查询要求子矩阵总和超过$L \cdot R \cdot \text{LCM}$，我们将组件分开：在索引上维护一个 2D 贡献网格，其中每个更新对应于一个矩形加法，并通过前缀和回答查询。 

这导致了一个基于维护每个$R$段列表$[L_1, L_2)$,$[L_2, L_3)$, ...其中每个段对于以以下结尾的子数组共享相同的 LCM$R$。 每个段贡献一个恒定值次$L$，允许前缀累积超过$L$。

 | 蛮力 |$O(n^3 \log A)$|$O(1)$| 太慢了|
 | 最佳 |$O(n \log A + Q \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们通过修复右端点并维护以该处结束的子数组的所有可能的 LCM 状态来处理贡献，并将其压缩为左端点的不相交段。 

1. 迭代$R$从 1 到$n$，将其视为我们当前正在考虑的子数组的右边界。 这确保了每个子数组在处理其右端点时只计算一次。 
2. 维护一个配对列表$(\ell, \text{lcm})$表示对于左端点段中的所有起始点，结束于的子数组的 LCM$R$是恒定的。 最初此列表仅包含$(R, a_R)$，因为长度为 1 的子数组的 LCM 等于其元素。 
3. 扩展之前的状态$R-1$到$R$通过结合$a_R$与所有现有的 LCM 值一起使用$\text{lcm}(x, a_R)$。 当我们计算这些新值时，我们将具有相同 LCM 的相邻段合并，确保列表保持压缩状态。 
4. 合并时，每当两个段产生相同的 LCM 时，我们将它们统一为一个更大的区间。 这一点至关重要，因为 LCM 相等意味着所有中间起始点对于该正确端点的行为都相同。 
5. 对于每个段$[\ell_i, \ell_{i+1})$具有LCM值$v_i$，我们计算其对固定的总贡献$R$作为$$v_i \cdot R \cdot \sum_{L=\ell_i}^{\ell_{i+1}-1} L$$内部总和是使用算术级数公式计算的。 

1. 我们将贡献存储在前缀结构中$L, R$，使得任意查询矩形$[l, r]$可以回答为子矩阵和$O(1)$或者$O(\log n)$取决于实施。 
2. 使用预先计算的 2D 前缀和回答每个查询。 

关键思想是，我们不是明确地跟踪所有子数组，而是跟踪子数组如何以每个子数组结尾$R$用相同的 LCM 值划分左边界空间。 

### 为什么它有效

 对于固定的右端点$R$，每个子数组结束于$R$仅由其起始索引确定。 当我们向左移动时，只有当遇到引入新素数指数最大值的元素时，LCM 才会发生变化。 这意味着开始时的 LCM 在连续段上是分段常数$L$。 由于这些段是不相交的并且覆盖了所有有效的开始，因此对它们进行求和可以准确地重建以$R$。 汇总所有$R$恰好覆盖每个子数组一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def lcm(x, y):
    import math
    return x // math.gcd(x, y) * y

n = int(input())
a = list(map(int, input().split()))
q = int(input())
queries = [tuple(map(int, input().split())) for _ in range(q)]

# 2D prefix over contributions
pref = [[0] * (n + 2) for _ in range(n + 2)]

for r in range(1, n + 1):
    cur = []
    cur.append((r, a[r - 1]))

    for l, val in prev:
        nv = lcm(val, a[r - 1])
        if cur and cur[-1][1] == nv:
            cur[-1] = (cur[-1][0], nv)
        else:
            cur.append((l, nv))

    prev = cur

    for i in range(len(cur)):
        l1 = cur[i][0]
        l2 = cur[i + 1][0] if i + 1 < len(cur) else r + 1
        v = cur[i][1]

        add = v * r % MOD

        pref[r][l1] = (pref[r][l1] + add * (l1 + l2 - 1) * (l2 - l1) // 2) % MOD

# build 2D prefix
for i in range(1, n + 1):
    for j in range(1, n + 1):
        pref[i][j] = (pref[i][j] + pref[i - 1][j] + pref[i][j - 1] - pref[i - 1][j - 1]) % MOD

for l, r in queries:
    ans = (pref[r][r] - pref[l - 1][r] - pref[r][l - 1] + pref[l - 1][l - 1]) % MOD
    print(ans)
```该代码遵循为每个右端点构建贡献并压缩左端点上的 LCM 状态的思想。 这`prev`结构存储以前一个索引结尾的子数组的 LCM 值的分段。 对于每个新位置，我们通过使用新元素计算 LCM 并合并相等值来扩展所有先前的段。 

这`pref`表的目的是累积贡献，以便每个单元格$(l, r)$表示右端点为的子数组的总贡献$r$并且其左端点至少是$l$。 最终的查询提取在此 2D 结构上使用包含-排除。 

计算算术和时必须注意整数除法，因为左段和是使用连续整数和的公式计算的。

为了$r=2$，子数组是$[2,2]$有价值$2 \cdot 2 \cdot 2 = 8$， 和$[1,2]$LCM 2 贡献$2 \cdot 1 \cdot 2 = 4$。 总计为$r=2$是 12。 

对于$r=3$，子数组是：$[3,3]=9$,$[2,3]=6 \cdot 2 \cdot 3=36$,$[1,3]=6 \cdot 1 \cdot 3=18$, plus previous contributions carried consistently. 总数变为 94。

 ## 边缘情况

 像这样的最小情况$n=1$测试算法是否在不依赖段合并的情况下正确处理单个子数组。 贡献很简单$a_1 \cdot 1 \cdot 1$，并且任何分段逻辑都不能意外地跳过初始化。 

统一数组，例如$[5,5,5]$强调合并逻辑。 由于 LCM 不会因扩展而改变，因此所有以给定结尾的子数组$R$必须折叠成一个片段。 如果合并不正确，这种情况将由于重复的段而产生夸大的计数。 

严格递增的素重数组，例如$[2,3,5,7]$测试LCM的快速增长。 每个扩展都会改变 LCM，因此分段变得最大程度地碎片化。 当每个起始索引形成自己的段时，算法仍必须保持正确性，确保不会发生过度合并。
