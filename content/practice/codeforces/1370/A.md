 ## 解决方案
 ## 问题理解

 我们被要求找到从 1 到 n 的所有不同整数对中最大可能的最大公约数。 对于给定的 n，我们需要任意两个数字 a 和 b 的最大 gcd，其中 1 ≤ a < b ≤ n。 输入由多个测试用例组成，每个测试用例指定一个 n 值，并且输出是每个测试用例的单个整数。 

约束告诉我们 n 最多可以达到 10^6，并且最多可以有 100 个测试用例。 在最坏的情况下，尝试所有整数对的简单解决方案将执行大约 n²/2 gcd 计算。 对于 n = 10^6，这大约是 5 × 10^11 次操作，太大而无法在一秒钟内运行。 我们需要一种相对于 n 以近线性或对数时间运行的方法。 

边缘情况包括最小的 n = 2，其中唯一的对是 (1, 2) 并且 gcd 为 1。当 n 为奇数与偶数时，会出现另一个微妙之处。 例如，如果 n = 3，则对为 (1, 2)、(1, 3)、(2, 3)，所有这些对的 gcd 均为 1。对于 n = 5，对 (2, 4) 的 gcd 为 2，大于 1。任何不考虑这些模式的解决方案都可能会低估最大 gcd。 

## 方法

 蛮力方法很简单：迭代所有对 (a, b)，计算每个对的 gcd(a, b)，并跟踪最大值。 这是正确的，因为它直接测试每个可能的组合，但是当 n 达到 10^6 时，它太慢了。 对于 t = 100 个测试用例，在最坏的情况下需要超过 10^13 次操作，这显然是不切实际的。 

最佳方法取决于最大可能 gcd 必须至少为 n//2 的观察结果。 考虑数字 n 本身。 如果我们寻找与 gcd k 形成一对的 k ≤ n 的倍数，则 [1, n] 中允许两个不同倍数的最大 k 是 n//2。 这是有效的，因为当 k ≤ n//2 时，对 (k, 2k) 始终处于范围内。 任何更大的 k 值都不能在该范围内产生两个不同的倍数。 因此，对于每个n，最大gcd就是n//2。 

这种见解将问题简化为每个测试用例的单个整数除法，从而使每个用例的解决方案为 O(1)，总体为 O(t)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳| 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取测试用例数t。 这告诉我们需要处理多少个独立的 n 值。 
2. 对于每个测试用例，读取整数n。 
3. 使用整数除法计算 n 除以 2。 将此值赋给 max_gcd。 这是可行的，因为 [1, n] 中至少有两个倍数的最大整数恰好是 n//2。 
4. 输出该测试用例的 max_gcd。 
5. 对所有测试用例重复步骤 2-4。 

原理：对于任何 k > n//2，[1, n] 中 k 的唯一倍数是 k 本身，它不能形成一对不同的数字。 对于 k ≤ n//2，对 (k, 2k) 有效，确保 gcd k。 因此 n//2 是所有对中可能的最大 gcd。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    print(n // 2)
```该代码读取测试用例的数量，然后迭代每个 n。 整数除法运算符`//`确保我们始终向下舍入，这对于奇数 n 值至关重要。 计算后直接打印可以避免存储不必要的数据，并最大限度地减少内存使用。 

## 工作示例

 样本1：

 | n | n // 2 | 最大gcd |

 | 3 | 1 | 1 |

 (1, 2) 或 (1, 3) 或 (2, 3) 的 gcd 都为 1。n//2 正确地给出 1。 

样本2：

 | n | n // 2 | 最大gcd |

 | 5 | 2 | 2 |

 对 (2, 4) 的 gcd 为 2，这是最大值。 n//2 正确识别了这一点。 

这些迹线表明，对于较小的奇数和偶数 n，算法都会选择正确的最大 gcd。

 ## 边缘情况

 对于 n = 2，唯一的对是 (1, 2)。 该算法计算出 2//2 = 1，这与实际的最大 gcd 相匹配。 对于像 7 这样的奇数 n，具有最大 gcd 的最大对是 (3, 6)，给出 gcd 3。算法输出 7//2 = 3，正确识别了这一点。 对于较大的 n = 10^6，该算法计算 500000，这是该对 (500000, 1000000) 的 gcd，证明该解决方案可以毫无问题地扩展到上限约束。
