 ## 解决方案
 ## 问题理解

 我们得到一个长度的数组$2n$。 我们可以永久删除两个元素。 之后，剩余的$2n-2$元素必须分成对。 每对都被其两个元素的和替换，生成一个数组$b$长度$n-1$。 

要求不是关于构建过程本身，而是关于最终的数组：中的每个数字$b$必须共享一个大于 1 的公约数。换句话说，所有对和必须同时能被某个整数整除$d > 1$。 

任务不是找到 gcd 值，而是显式输出哪些索引配对以使该条件成立。 

限制很小：$n \le 1000$最多 10 个测试用例。 这立即排除了对所有元素配对的任何繁重的组合搜索，因为配对结构已经具有阶乘增长。 即使对删除对进行二次检查也是可以接受的，因为在最坏的情况下我们检查$O(n^2)$候选人和每次检查都是线性的。 

一个微妙的问题是 gcd 条件的限制程度。 使各个对能够被每对独立选择的某个数字整除是不够的。 相同的除数必须同时适用于所有对和。 这使得局部贪婪配对策略不可靠，除非它们明确强制执行共享结构，例如模块化约束。 

一个幼稚的错误是贪婪地配对任意元素而不考虑全局可分性。 例如，将输入中的最小元素与最大元素或相邻元素配对并不能保证所有总和共享一个公约数。 另一种失败模式是选择固定配对策略，例如始终配对$i$和$i+1$，它忽略了 gcd 约束所需的算术结构。 

关键的困难在于，我们必须首先删除两个元素，使剩余的多重集与统一的模块化模式“兼容”，然后我们才能在该结构内自由配对。 

## 方法

 一个蛮力的想法是尝试所有丢弃两个元素的方法，然后尝试以某种有效的方式将剩余元素配对，检查结果和是否存在公共 gcd。 即使我们修复配对策略，删除两个元素的方法数量也是$O(n^2)$，对于每一个，我们仍然需要验证是否存在有效的配对，并可能构建它，如果天真地这样做，这可能会变得复杂。 

关键的观察是我们实际上不需要单独搜索配对和 gcd 值。 如果所有对和都可以被某个数字整除$d$，那么每对必须满足局部模条件。 一个特别有用的选择是$d = 3$，因为余数模 3 形成一个封闭的配对系统：$0+0$和$1+2$两者都给出 3 的倍数。这减少了问题，以确保在删除两个元素后，剩余的模 3 的残基计数可以在这些规则下完美配对。 

因此，我们不是直接构建配对，而是寻找两个元素的良好去除方式，使得残基计数在结构上变得平衡：所有元素都可以配对成$(0,0)$或者$(1,2)$对。 一旦这个条件成立，配对本身就会变得直接而贪婪。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对所有删除进行强力配对验证 |$O(n^3)$或者更糟|$O(n)$| 太慢/难以实施|
 | 尝试所有移除+模块化可行性检查+贪婪构建|$O(n^3)$最糟糕的是，$O(n^2)$实用|$O(n)$| 已接受 |

 ## 算法演练

 ### 关键思想

 我们以 3 为模，并尝试强制执行一个所有对和都可以被 3 整除的结构。 

### 步骤

 1. 计算$a_i \bmod 3$对于所有元素并按残基类别跟踪它们的索引。 

这是必要的，因为只有残基才对配对可行性产生影响。 
2. 尝试删除所有可能的索引对$(i, j)$。 

去除它们后，我们模拟剩余的残留物计数。 
3. 对于每次移除，计算计数$c_0, c_1, c_2$对于剩余元素中的残基 0、1 和 2。 
4. 检查这些计数是否满足两个条件：

 余数 1 元素的数量等于余数 2 元素的数量，余数 0 元素的数量是偶数。 

这确保了所有元素都可以划分为有效对，其总和可被 3 整除。 
5. 找到有效的删除后，通过配对构建答案：

 首先将所有剩余的 0 残基元素任意成对，然后将剩余的 1 残基元素与 2 残基元素配对。 
6. 输出所有构造对的索引。 

我们只需要尝试删除对的原因是该问题保证至少存在一个有效配置，并且$n \le 1000$允许$O(n^2)$搜索。 

### 为什么它有效

 不变的是我们对其余元素强制执行全局模块化结构。 如果$c_1 = c_2$，每个 1 都可以与 2 匹配，产生的总和可被 3 整除。如果$c_0$是偶数，所有剩余的 0 残基彼此配对，也产生 3 的倍数。由于每个元素在一对中仅使用一次，因此每个所得的和都可以被 3 整除，因此所有和的 gcd 至少为 3。 

丢弃的两个元件正是允许将残留物计数调整到这种平衡配置的原因。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_pairs(indices, res):
    # returns list of pairs (i, j)
    pos = {0: [], 1: [], 2: []}
    for idx in indices:
        pos[res[idx]].append(idx)

    pairs = []

    # pair 0 with 0
    while len(pos[0]) >= 2:
        a = pos[0].pop()
        b = pos[0].pop()
        pairs.append((a, b))

    # pair 1 with 2
    while pos[1] and pos[2]:
        a = pos[1].pop()
        b = pos[2].pop()
        pairs.append((a, b))

    return pairs

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    res = [x % 3 for x in a]
    m = 2 * n

    found = False

    for i in range(m):
        if found:
            break
        for j in range(i + 1, m):
            remaining = []
            for k in range(m):
                if k != i and k != j:
                    remaining.append(k)

            c = [0, 0, 0]
            for idx in remaining:
                c[res[idx]] += 1

            if c[1] == c[2] and c[0] % 2 == 0:
                pairs = build_pairs(remaining, res)
                for x, y in pairs:
                    print(x + 1, y + 1)
                found = True
                break
```该解决方案首先将值转换为余数类 mod 3，因为这是保证和的稳定配对条件的结构。 然后，它尝试所有可能的丢弃对，并检查剩余的多重集是否满足完全配对的必要和充分条件。 

构造步骤通过残差分隔索引并贪婪地形成有效对。 顺序并不重要，因为可行性保证每个组都具有精确匹配的结构。 

一个微妙的实现细节是，由于输出需要原始位置，因此始终使用索引而不是值。 这可以避免值重复时出现歧义。

 ### 示例 1

 输入：```

 0-残基彼此之间，1与2之间。

                    c[res[idx]] += 1

                    pos = {0: [], 1: [], 2: []}
                    for idx in remaining:
                        pos[res[idx]].append(idx)

                    pairs = []
                    while len(pos[0]) >= 2:

 ## 边缘情况

 一个关键的边缘情况是当许多值共享相同的残基类别时，这可能会引发贪婪的配对，而忽略平衡其他残基类别的需要。 例如，如果大多数数字与 1 模 3 全等，则任意配对它们都会失败，因为无法匹配剩余的残数 2 元素。 

另一个微妙的情况是，当看似有效的删除留下一个结构时，即使总数看起来平衡，配对在结构上也是不可能的，这就是为什么显式条件$c_1 = c_2$和$c_0$甚至是必要且充分的。 该算法直接检查这一点，避免错误的贪婪假设。
