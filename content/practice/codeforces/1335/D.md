 ## 解决方案
 ## 问题理解

 我们从一个完全有效的数独网格开始。 每行、每列和每个 3 x 3 子网格只包含数字 1 到 9 一次。 任务是通过修改最多九个单元来稍微破坏这个结构，以便以一种非常具体的方式打破数独的每个结构约束：每行必须包含一个重复值，每列必须包含一个重复值，并且每个 3 x 3 块也必须包含一个重复值。 

关键点是我们并不是试图制作一个随机的无效网格。 我们被迫同时破坏_所有三种类型的唯一性约束_，同时更改很少的单元格。 

就测试用例的数量而言，输入大小很大，最多可达 10^4，但每个测试用例都是固定的 9 x 9 网格。 这使得每次测试的处理预算极其紧张，这意味着任何解决方案每个单元都必须是 O(1)，并且没有搜索或回溯。 任何涉及尝试更改组合或重复验证配置的想法在规模上都会太慢。 

一个微妙的限制是我们最多可以更改 9 个单元格。 这个数字并非偶然。 由于有 9 行、9 列和 9 个块，一个自然的想法是我们可能需要恰好“接触”每个结构单元一次，这表明每行一个单元格的模式或类似的全局构造。 

一种天真的但诱人的方法是尝试大量修改单行或单列。 这会立即失败，因为仅更改一行并不能保证所有列和块也包含重复项。 例如，如果我们仅修改第 1 行，则第 1 至第 9 列可能仍保留 1 至 9 的排列，从而保留列有效性并违反要求。 

另一个常见的失败情况是每当行或列看起来“太正确”时贪婪地更改随机单元格。 由于数独中的所有行和列都是排列，因此局部贪婪更改可以轻松修复一个约束，同时无意中保留其他约束。 

## 方法

 强力解释是尝试更改最多 9 个单元格的所有方法，并针对每个配置检查每行、列和块是否包含重复项。 从 81 个单元格中选择最多 9 个单元格的方法数量已经非常多了，对于每个选择，我们需要尝试 8^k 次值更改。 这是完全不可行的。 

关键的观察是结构性的：我们根本不需要推理数独内容。 我们只需要破坏每一行、每一列、每一块的排列属性即可。 由于当前每行只包含 1 到 9 的所有数字一次，因此行中的任何重复值都会立即违反行条件。 这同样适用于列和块。 

这提出了一种建设性的策略：通过改变精心选择的对称位置来强制碰撞，以便在所有行、列和块中同时引入重复项。 最简单的方法是按照 3 x 3 块分解对齐的模式修改单元格。 

标准构造是精确更改每个 3 x 3 块内行索引和列索引满足一致偏移模式的单元格。 这可确保每一行、每一列和每个块都至少收到一个重复值。 

表达这一点的一种简洁方法是：对于每个块，我们精确修改其内部的对角单元格。 也就是说，对于从 (3r, 3c) 开始的每个块，我们修改 (3r, 3c)、(3r+1, 3c+1)、(3r+2, 3c+2)。 更改整个网格中的这 9 个单元格可以保证每一行、每一列和每一块都失去唯一性，因为每个结构单元都至少获得一个由受控覆盖模式引起的重复数字。

为了确保重复，我们在考虑全局模式后将每个选定的单元格替换为已出现在其行或列中的值。 一个方便的技巧是以将每个选定单元格映射到同一行/列结构中的另一个选定单元格的方式循环移位数字，从而强制重复。 

这是可行的，因为我们并不是试图保持数独的有效性；而是要保持数独的有效性。 我们故意以受控的网格对齐模式引入碰撞。

 ## 算法演练

 我们采用的想法是选择一组固定的位置，这些位置在所有 3 x 3 块中形成一致的模式，然后在这些位置内移动值。 

1. 识别网格的 3 x 3 块结构。 每个块由左上角 (0,0)、(0,3)、(0,6)、(3,0) 等定义。 
2. 在每个块内，选择对角线位置 (i, j)，其中 i 和 j 在块内具有相同的偏移量。 具体来说，如果块从 (r, c) 开始，我们选择 (r, c)、(r+1, c+1)、(r+2, c+2)。 这总共给出了 9 个单元格。 
3. 对于每个选定的单元格，将其值替换为保证出现在同一行或列中的另一个选定位置的不同数字。 一个简单的确定性选择是将每个数字 x 替换为 (x mod 9) + 1，这确保没有数字保持固定。 
4. 将修改后的网格写入为输出。 

重要的想法是我们不依赖修改后的数独结构。 我们只依赖这样一个事实：所选位置以结构化方式与每行、每列和每个块相交，以保证重复。 

### 为什么它有效

 每行在每个受影响的块行模式中恰好包含一个修改的单元格，并且替换值是从现有数字的循环映射中选择的。 因为映射是单射的而不是恒等的，所以至少两个相同的值被强制进入修改位置的每一行。 同样的推理也适用于列和块，因为所选单元格形成 3 x 3 块分解的完整横截面。 这确保每个结构单元至少包含一个重复值，满足反数独条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        g = [list(input().strip()) for _ in range(9)]

        for i in range(9):
            for j in range(9):
                # pick diagonal cells inside each 3x3 block
                if i % 3 == j % 3:
                    # shift digit cyclically
                    g[i][j] = str((int(g[i][j]) % 9) + 1)

        for row in g:
            print("".join(row))

solve()
```该实现扫描每个单元并应用一个简单的局部规则：如果单元位于其 3 x 3 块的内部对角线上，则它会被修改。 条件`i % 3 == j % 3`精确编码每个块内的对角线对齐。 

替代品`(digit % 9) + 1`确保每个更改的值都与原始值不同，同时保持在 1 到 9 的范围内。由于我们只触及单元格的一个结构化子集，因此我们保持在每个网格最多 9 次修改的限制内。 

打印的顺序很重要：在进入下一个测试用例之前，我们必须输出每个测试用例的完整修改网格。

 ## 边缘情况

 一种边缘情况是当输入已经具有以某种方式对齐的数字时，天真的修改可能会意外地保留列中的唯一性。 例如，如果列在转换后已包含重复的数字，则粗心的模式可能会错过打破某些块约束的情况。 对角线选择避免了这种情况，因为它保证每个块恰好贡献一个修改的单元，从而防止任何结构的隔离。 

另一种情况是具有相同网格的多个测试用例。 由于该算法不存储测试之间的状态并直接根据输入重新计算，因此每个网格都是独立处理的并产生一致的修改。 

最后一个微妙的情况是确保修改后的值保持在 1 到 9 之间。循环变换`(x % 9) + 1`无需分支或查找表即可保证这一点，从而避免意外的无效数字。
