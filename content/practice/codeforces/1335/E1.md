 ## 解决方案

 ## 问题理解

 我们得到一个整数序列，并要求提取一个具有非常特定结构的子序列。 子序列必须看起来像重复值的块`x`，后跟一个重复值块`y`，后跟相同的值`x`。 允许两个值相等，这会将结构折叠成单个统一块。 

任务不是构造任何有效的子序列，而是在此约束下最大化其长度。 由于我们可以在保留顺序的同时自由删除元素，因此问题实际上在于选择左侧块的起始位置、中间块的位置以及我们可以重用两端的匹配元素的程度。 

约束条件`n ≤ 2000`每个测试用例，还有总和`≤ 2000`，表明`O(n^3)`每个测试的解决方案太慢，但是`O(n^2)`或者`O(n^2 log n)`是可以接受的。 小字母表大小（值最多 26）是一个重要提示：我们可以尝试所有值对`(x, y)`。 

一个幼稚的错误是直接尝试所有子序列或尝试在没有结构的情况下对所有子串进行 DP，这会导致立方行为或更糟。 另一个微妙的问题是假设中间块在原始数组中必须是连续的，这是错误的，因为我们正在处理子序列。 

边缘情况包括所有值都相等的数组、最佳解决方案仅使用一个值的数组以及最佳结构使用非常小的中间块甚至空中间的情况。 

例如，在`[1, 1, 1, 1]`，最好的答案是`4`，通过选择实现`x = 1, y = 1`。 粗心的方法迫使`x ≠ y`会错误地减少答案。 

另一个例子是`[1, 2, 3, 2, 1]`。 它看起来是对称的，但它是无效的，因为中间不能支持一致的块结构，同时保留子序列约束。 

## 方法

 蛮力思想是选择值`x`和`y`，然后尝试构建形式的最佳子序列`x...x y...y x...x`。 对于固定`(x, y)`，我们将扫描数组并决定有多少`x`我们可以从左边取多少个`y`我们可以在中间取多少个`x`从右边。 如果我们尝试明确地分割位置，我们最终会检查分割点的所有三元组，即`O(n^3)`每对，并且有 26 个值，这变得太慢了。 

关键的观察是外部块仅取决于出现的次数`x`我们可以从前缀和后缀中获取，而中间块取决于所选边界之间的子数组。 我们没有明确选择边界，而是固定了`x`从两端取出，说`k`，然后查看之间的段`k`从左边算起第 - 次出现`k`从右侧第 - 次出现。 在该段内，我们只需要某个值的最佳频率`y`。 

所以对于每个值`x`，我们预先计算它的出现位置。 我们尝试一切可能`k`这样我们就可以采取`k`两端都有发生。 对于每一对这样的边界位置，我们扫描中间段并计算任何值的最大频率`y`。 答案是`2k + best_middle`。 

这将问题减少到`O(26 * n^2)`，因为对于每个`x`我们尝试达到`O(n)`的值`k`，每个中间扫描是`O(n)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(26²·n3) | O(n) | 太慢了|
 | 最佳 | O(26·n²) | O(26·n²) | O(n) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 为从 1 到 26 的每个值建立一个位置列表。这使我们能够快速知道每个值出现的位置，这对于修复外部块至关重要。 
2. 对于每个值`x`，考虑选择对称外部块的所有可能方法。 如果`pos[x]`包含`m`发生的情况，我们尝试`k = 0`到`m // 2`。 这代表采取`k`从一开始就发生的事件和`k`从最后。 这保证了有效的子序列结构，因为索引不断增加。 
3. 对于每个`k`，定义左边界为`pos[x][k - 1]`右边界为`pos[x][m - k]`。 中间部分是严格介于这两个指数之间的所有内容。 
4. 扫描中间段并计算所有值的频率计数`y`。 最佳可能的中间块是该段中所有值中的最大频率。 这是可行的，因为中间块必须是单个重复值。 
5. 更新答案`2 * k + best_middle`。 
6. 还要考虑我们不采用外部块的情况，这会减少查找整个数组中最频繁元素的问题。 

### 为什么它有效

 该构造将子序列分成独立的结构决策。 一旦外`k`对`x`是固定的，任何有效的完成仅取决于中间间隔中的元素的多重集。 由于中间必须是单个重复值，因此最佳选择就是该区间中最频繁的元素。 每个有效的解决方案都对应于一个选择`x`,`k`， 和`y`，因此枚举所有这样的三元组就覆盖了整个解空间，没有重复或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pos = [[] for _ in range(27)]
        for i, v in enumerate(a):
            pos[v].append(i)

        ans = 1

        # case: single block (x == y or y empty)
        freq = [0] * 27
        for v in a:
            freq[v] += 1
            ans = max(ans, freq[v])

        # try outer value x
        for x in range(1, 27):
            m = len(pos[x])
            if m == 0:
                continue

            for k in range(m // 2 + 1):
                l = pos[x][k - 1] + 1 if k > 0 else 0
                r = pos[x][m - k] - 1 if k < m else -1

                if l > r:
                    ans = max(ans, 2 * k)
                    continue

                cnt = [0] * 27
                best_mid = 0

                for i in range(l, r + 1):
                    cnt[a[i]] += 1
                    if cnt[a[i]] > best_mid:
                        best_mid = cnt[a[i]]

                ans = max(ans, 2 * k + best_mid)

        print(ans)

if __name__ == "__main__":
    solve()
```该实现首先计算全局频率来处理退化情况，其中最佳答案只是一个常数子序列。 

对于每个候选外部值`x`，我们迭代可能的对称计数`k`。 指数`l`和`r`移除后仔细定义内部部分`k`两端都有发生。 边界逻辑至关重要：`pos[x][k - 1] + 1`确保我们排除左边的块，并且`pos[x][m - k] - 1`排除右侧块。 

中间扫描每个配置使用新的频率阵列。 尽管这看起来是重复的，但由于小的限制，总的复杂性仍然可以接受。

 ## 边缘情况

 在单元素数组中，例如`[5]`，每个配置都简化为空的外部块或单个中间元素。 该算法自然会处理这个问题，因为`k = 0`导致全范围，最佳频率为 1。 

在全相等的数组中，例如`[7,7,7,7,7]`, 每一个选择`x`和`k`产生一个有效的结构，并且中间频率等于剩余计数。 最优值成为整个数组长度，这是在以下情况下实现的：`x = y = 7`。 

在稀疏数组中，例如`[1,2,3,4]`，没有值重复足以形成有意义的外部块，所以所有`k > 0`案例失败或贡献较小。 全局频率初始化确保答案正确回落到 1。
