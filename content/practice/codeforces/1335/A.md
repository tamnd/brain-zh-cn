 ## 解决方案

 ## 问题理解

 我们正在将一堆相同的糖果分成两个正部分。 每个测试用例给出一个编号`n`，我们想要计算有多少个不同的有序对`(a, b)`存在使得两者`a`和`b`是正整数，它们的总和为`n`，并且第一部分严格大于第二部分。 

尽管糖果无法区分，但顺序很重要，因为爱丽丝和贝蒂是不同的人，并且约束`a > b`自动删除对称重复项。 

从约束角度来看，测试用例的数量可以多达10,000个，并且每个测试用例的数量可以达到10,000个。`n`最大可达 2×10^9。 这立即排除了任何尝试枚举所有对的解决方案`(a, b)`最多`n`，因为每个测试用例都是线性的并且太慢了。 预期的解决方案必须在每个测试用例的恒定时间内计算答案。 

幼稚推理的一个微妙的失败案例来自于忘记了严格的不平等。 例如，当`n = 4`，有效的分割是`(3,1)`仅有的。 这对`(2,2)`即使求和正确，也是无效的，并且缺少该条件会导致计数过多。 另一个常见的错误是治疗`(a, b)`和`(b, a)`作为两个有效的选择，这会重复计算并完全破坏排序条件。 

## 方法

 蛮力策略会尝试所有可能的值`a`从`1`到`n - 1`, 计算`b = n - a`，并计算如果`a > b`。 这是正确的，但它检查粗略`n`每个测试用例的候选者，在单个输入的最坏情况下大约变为 2×10^9 次操作，总共最多 10^13 次操作。 那是完全不可行的。 

关键的观察是一旦`a + b = n`，选择`a`自动修复`b`，所以问题简化为计算有多少个整数`a`满足两者`a > n - a`和`a > 0`。 不等式简化为`2a > n`， 所以`a > n/2`。 

同时，我们还必须确保`b = n - a > 0`，这意味着`a < n`。 所以有效值`a`是严格大于的整数`n/2`并且严格小于`n`。 

这将问题转化为计算连续区间内的整数，可以直接使用算术而不是迭代来计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每个测试用例 O(n) | O(1) | O(1) | 太慢了|
 | 最佳 | 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.观察任何有效分布完全由选择决定`a`， 自从`b = n - a`。 这将问题简化为计算有效值`a`。 
2. 平移约束`a > b`使用替换将不等式转化为：`a > n - a`。 
3. 重新排列不等式以隔离`a`, 给予`2a > n`，这意味着`a > n/2`。 
4. 将其与积极约束相结合。 自从`b > 0`，我们必须有`a < n`，并且自从`a > 0`已经由以下保证`a > n/2`为了`n ≥ 1`，有效范围为`a ∈ (n/2, n)`。 
5. 计算该范围内的整数。 最小的有效整数是`floor(n/2) + 1`，最大的是`n - 1`。 因此计数为`(n - 1) - (floor(n/2) + 1) + 1`，这简化为`n//2 - 1 + 1 = (n - 1) // 2`。 
6. 为每个测试用例返回该值。 

### 为什么它有效

 每个有效的分割恰好对应一个整数`a`在范围内`(n/2, n)`，并且每个这样的整数都会产生一个有效的`b = n - a`这是正数并且严格小于`a`。 有效分割和有效分割之间的映射`a`值是一对一的，因此计数有效`a`值相当于计算有效分布。 不包含无效对，因为不等式确保了正性和严格的排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    print((n - 1) // 2)
```该解决方案读取每个测试用例并直接应用导出的公式。 表达式`(n - 1) // 2`精确捕获严格大于的整数个数`n/2`并且小于`n`。 整数除法可确保正确的向下取整行为，而无需浮点运算。 

一个常见的陷阱是使用`n // 2`相反，对于偶数值，该值会减少 1`n`，因为它错误地包括了中点情况，其中`a = b`。

 ## 边缘情况

 对于`n = 1`，无法分成两个正数部分，因为两个正整数的最小和为 2。该公式给出`(1 - 1) // 2 = 0`，它匹配空的有效对集。 

为了`n = 2`，唯一可能的分裂是`(1,1)`，但它违反了`a > b`，所以正确答案是 0。公式给出`(2 - 1) // 2 = 0`，正确排除对称中点情况。 

对于甚至`n`， 例如`n = 10`，这对`(5,5)`不允许，因此计数仅包含严格高于一半的值。 由于推导中包含严格的不等式，该公式自然排除了中点。 

对于大型`n`喜欢`2 × 10^9`，Python 中不会出现溢出问题，并且每个测试用例的计算仍然是单个整数运算，从而保持了正确性和效率。
