 ## 解决方案
 ## 问题理解

 每个商店都有一个取决于售价的线性需求模型。 如果我们设定一个价格$p$， 店铺$i$贡献需求$a_i - b_i p$，每售出一个单位都会产生利润$p - c_i$。 该商店的总利润是这两个表达式的乘积。 在一系列商店中，总利润只是每家商店贡献的总和。 

查询给出一段连续的商店。 对于该细分市场，我们可以选择单一的全球价格$p$这适用于该细分市场中的所有商店，我们希望实现总利润最大化。 

因此输入由数组组成$a_i$,$b_i$,$c_i$，以及多个查询，每个查询都要求在选择最佳价格时在子数组上获得最佳可实现利润。 

这些约束的设计使得如果有很多查询，每个查询的线性扫描就会太慢。 如果$n, q$都很大，一个$O(nq)$解决方案将涉及最多$10^{10}$操作，这远远超出了两秒内的可行极限。 这立即将我们推向一种解决方案，在预处理后，每个查询都会在恒定或对数时间内得到答复。 

在两种情况下会出现一个微妙的问题。 首先，需求变为零或负，如果$p$很大，因此不受约束的数学最佳值可能会超出有效的定价范围。 二、如果全部$b_i = 0$在一个细分市场中，利润呈线性关系$p$，因此“抛物线顶点”论证不成立。 

一个具体的小失败案例：如果全部$b_i = 0$，那么利润就变成了$\sum a_i (p - c_i)$，其无界增加为$p$增加，因此简单的顶点公式除以零或产生无意义的结果。 当最优价格高于最高允许价格时，会发生另一种边缘情况$m$，其中答案必须在边界处而不是在无约束的最优处进行评估。 

## 方法

 修复查询段$[l, r]$。 对于单个店铺来说，扩大利润表达式可以得到：$$(a_i - b_i p)(p - c_i) = -b_i p^2 + (a_i + b_i c_i)p - a_i c_i.$$对线段求和保留了二次结构。 总利润变为：$$-Ap^2 + Bp - C,$$在哪里：$$A = \sum_{i=l}^r b_i,\quad B = \sum_{i=l}^r (a_i + b_i c_i),\quad C = \sum_{i=l}^r a_i c_i.$$这是一条凹抛物线$p$，因此最大值出现在其顶点$p = \frac{B}{2A}$， 假如$A > 0$。 

暴力解决方案将重新计算$A$,$B$， 和$C$通过扫描段来针对每个查询，然后以候选最优价格评估抛物线。 那成本$O(n)$每个查询，因为每个查询都需要在一个范围内求和。 

关键的观察结果是，该段仅聚合了三个线性统计数据。 一旦我们预先计算了前缀和$b_i$,$a_i + b_i c_i$， 和$a_i c_i$，我们可以检索$A$,$B$， 和$C$每次查询的时间恒定。 这将问题简化为在恒定数量的候选点处评估二次函数：顶点和附近的整数，加上边界约束。 

如果有最高允许价格$m$，最优值可能会被剪裁。 在这种情况下，我们将内部最优值与端点进行比较$0$和$m$，因为凹函数在受到约束时在顶点或边界处达到最大值。 

特殊情况$A = 0$完全删除二次项，留下线性函数$p$，所以最好的选择总是在边界处$m$。

 | --- | --- | --- | --- |
 | 蛮力 |$O(nq)$|$O(1)$| 太慢了|
 | Prefix sums + quadratic evaluation |$O(n + q)$|$O(n)$| 已接受 |

 ## 算法演练

 1. Precompute prefix sums for three sequences:$b_i$,$a_i + b_i c_i$， 和$a_i c_i$。 这允许通过减法在恒定时间内计算任何段总和。 这样做的原因是所有需要的表达式都是对索引的加法。 
2. 对于每个查询$[l, r]$，计算：$A = \sum b_i$,$B = \sum (a_i + b_i c_i)$， 和$C = \sum a_i c_i$。 这会重建该段的二次利润函数，而不对其进行迭代。 
3.如果$A = 0$，将利润视为线性$p$。 在这种情况下，函数是$Bp - C$，以最大允许价格最大化$m$。 
4. 否则计算无约束最优价格$p_0 = \frac{B}{2A}$。 这是抛物线的顶点，通过将导数设置为零而导出。 
5. 自从$p$实际上必须是整数，评估利润为$\lfloor p_0 \rfloor$和$\lceil p_0 \rceil$，因为凹二次函数在这些最接近的整数之一处达到最大值。 
6. 是否有最高允许价格$m$，也评估于$p = m$。 正确答案是所有有效候选者中最大的。 
7. 返回最佳评估利润。 

步骤 5 背后的原因是连续最优值可能不是整数，但凹性保证离散最优值位于顶点周围最接近的整数点。 

### 为什么它有效

 对于每个查询段，利润作为价格的函数是凹二次函数。 凹二次函数在实数域中具有单个全局最大值，并且当我们远离顶点时，其值严格减小。 当限制为整数时，最大值必须出现在围绕顶点的两个整数之一处，或者如果约束限制了域，则最大值必须出现在边界处。 由于前缀和精确地重建了该二次方程的系数，因此每个查询都简化为评估固定的小候选集，从而保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q, m = map(int, input().split())
    a = [0] + list(map(int, input().split()))
    b = [0] + list(map(int, input().split()))
    c = [0] + list(map(int, input().split()))

    pa = [0] * (n + 1)
    pb = [0] * (n + 1)
    pc = [0] * (n + 1)

    for i in range(1, n + 1):
        pa[i] = pa[i - 1] + b[i]
        pb[i] = pb[i - 1] + (a[i] + b[i] * c[i])
        pc[i] = pc[i - 1] + a[i] * c[i]

    def range_sum(pref, l, r):
        return pref[r] - pref[l - 1]

    for _ in range(q):
        l, r = map(int, input().split())

        A = range_sum(pa, l, r)
        B = range_sum(pb, l, r)
        C = range_sum(pc, l, r)

        def profit(p):
            return -A * p * p + B * p - C

        best = -10**30

        if A == 0:
            best = profit(m)
        else:
            p0 = B / (2 * A)

            for p in (int(p0), int(p0) + 1):
                if 0 <= p <= m:
                    best = max(best, profit(p))
            best = max(best, profit(0), profit(m))

        print(best)

if __name__ == "__main__":
    solve()
```该实现直接反映了代数。 前缀数组准确地存储重建每个段的二次方程所需的系数。 利润函数被评估为派生公式的直接转换。 

唯一微妙的一点是处理浮点顶点计算。 该代码仅计算附近的整数$p_0$，它避免了精度问题，同时仍然捕获由凹性保证的离散最优值。 

边界检查$0$和$m$确保顶点位于有效范围之外时的正确性。

 ## 边缘情况

 一个关键的边缘情况是当所有$b_i = 0$。 在这种情况下，二次项消失并且顶点公式除以零。 该算法明确检查这种情况并切换到评估边界价格$m$，它与函数的单调结构相匹配。 

当最优价格计算自$p_0 = \frac{B}{2A}$位于外面$[0, m]$。 在这种情况下，抛物线在有效范围内减小，并且仅评估$0$和$m$正确捕获最大值是因为当驻点不可行时，闭区间上的凹函数在端点处达到极值。 

最后，浮点舍入$p_0$如果处理不小心，可能会错误分类确切的顶点。 将评估限制为$\lfloor p_0 \rfloor$和$\lceil p_0 \rceil$确保任何舍入误差都不能跳过真正的最佳整数点，因为凹性保证最佳值与实值顶点相邻。
