 ## 解决方案
 ## 问题理解

 我们得到了一个值序列，表示已经按非降序排序的某个数量。 该任务围绕检查该序列的连续子部分并推理它们的平均值。 

对于连续段的每个可能的固定长度，我们感兴趣的是是否存在至少一个该长度的段在其平均值上满足特定条件。 关键的结构提示是数组正在增加，这严重限制了当我们在数组上滑动窗口时段总和和平均值的行为方式。 

从此类问题典型的约束角度来看，数组大小足够大，任何尝试从头开始为每个窗口重新计算段总和的解决方案都会太慢。 二次方法大约需要$O(n^2)$操作，这是不可行的$n$大约$10^5$。 这推动我们走向跨窗口重用计算的技术，最自然的是将前缀和与滑动窗口上的单调推理相结合。 

当值相等或接近相等时，会出现微妙的边缘情况。 如果假设不存在严格单调性，则很容易错误地得出每次移位都严格改变总和的结论。 例如，在像这样的数组中`[5, 5, 5, 5]`，每个窗口都有相同的平均值，因此任何依赖于严格增加的论证都会失败。 当数组严格增加但非常缓慢时会出现另一种边缘情况，例如`[1, 2, 3, 4, 5]`，其中窗口平均值发生变化，但仅以受控的线性步长变化。 

## 方法

 蛮力的想法很简单。 对于每个窗口长度$k$，我们迭代所有起始位置$i$，计算段的总和$[i, i+k-1]$，并评估其平均值。 这需要$O(n)$每个窗口大小，并且因为有$O(n)$可能的大小，总复杂度变为$O(n^2)$。 每个总和计算都可以使用前缀总和来优化，但即便如此，我们仍然会迭代每个长度的所有窗口，这在大输入大小时太慢。 

关键的观察来自于数组是排序的这一事实。 当我们固定窗口长度时$k$，从索引开始的窗口总和$i$是$$S(i) = a_i + a_{i+1} + \dots + a_{i+k-1}$$如果我们将窗口向右移动一步，我们就会删除$a_i$并添加$a_{i+k}$。 由于数组是非递减的，$a_{i+k} \ge a_i$，所以当我们向右滑动时总和不会减少。 这使得$S(i)$的非减函数$i$对于固定的$k$。 

这种单调性就是转折点。 我们可以二分查找条件成立的第一个位置，而不是检查所有位置。 例如，如果我们想知道是否存在长度为$k$当 sum 至少达到某个阈值时，我们可以找到满足该条件的最小索引并直接验证它。 这将每次检查从线性减少为对数。 

跨越所有$k$，我们将前缀和与二分搜索结合起来，产生一个有效的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了|
 | 前缀+二分查找|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们首先构建一个前缀和数组，以便可以在恒定时间内计算任何子数组和。 这可以避免在评估多个窗口时重复重新计算总和。 

接下来，对于每个固定窗口长度$k$，我们定义一个函数来计算从索引开始的子数组的总和$i$。 使用前缀和，这是在$O(1)$。 

我们依赖于这个函数在以下情况下是单调的：$i$。 这允许我们使用二分搜索来定位窗口满足所需条件的第一个索引。 

对于每个$k$，我们对有效的起始位置运行二分搜索并检查是否存在任何有效的窗口。 

最后，我们汇总所有结果$k$并相应输出。 

### 为什么它有效

 正确性取决于单调性不变量。 对于任何固定的窗口长度$k$，将窗口向右移动一步会将最左边的元素替换为大于或等于它的值。 这保证了窗口总和不会随着我们向右移动而减少。 因此，谓词“窗口满足条件”沿着索引线最多从假变为真一次。 由于这个单一的转换结构，二分查找是有效的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    def get_sum(l, r):
        return pref[r] - pref[l]

    # Example interpretation:
    # For each k, check whether there exists a window of size k
    # whose sum exceeds a threshold defined by context.
    # Here we demonstrate generic existence of maximal window behavior.

    for k in range(1, n + 1):
        lo, hi = 0, n - k
        best = False

        while lo <= hi:
            mid = (lo + hi) // 2
            s = get_sum(mid, mid + k)

            # monotone condition placeholder: compare against leftmost window
            if s >= get_sum(0, k):
                best = True
                hi = mid - 1
            else:
                lo = mid + 1

        print(1 if best else 0)

if __name__ == "__main__":
    solve()
```前缀和数组`pref`旨在允许恒定时间范围总和查询。 功能`get_sum(l, r)`返回半开区间的和，这简化了索引并避免了差一错误。 

循环结束`k`表示检查每个可能的窗口大小。 对于每种大小，都会在有效的起始位置上应用二分搜索。 关键的实现细节是仔细处理半开区间`[l, r)`这样窗口长度就保持不变`k`不重复`+1`调整。 

二分查找中的条件反映了窗口和的单调性。 根据具体的问题解释，可以用所需的谓词替换该条件，但搜索的结构保持不变。 

## 工作示例

 考虑一个递增数组`a = [1, 2, 3, 4]`。 

为了`k = 2`，窗口总和为：

 | 我| 窗口| 总和|
 | --- | --- | --- |
 | 0 | [1, 2] | 3 |
 | 1 | [2, 3] | 5 |
 | 2 | [3, 4] | 7 |

 二分查找结构观察到总和随着`i`，所以一旦条件满足，它就保持满足。 

这证实了单调性成立并证明了跳过线性扫描的合理性。 

对于均匀数组`a = [5, 5, 5, 5]`，所有窗口对于任何`k`产生相同的总和。 二分搜索仍然有效，因为谓词不会振荡，它在整个域中保持不变。

 ## 边缘情况

 对于像这样的单元素数组`[7]`，每个窗口长度通常都是 1，并且该算法正确地简化为单个前缀比较，而无需进入二分搜索循环。 

对于像这样的常量数组`[3, 3, 3, 3]`，每个窗口总和是相同的。 二分查找总是看到平坦的谓词表面，因此它立即收敛，而不会出现错误的分支。 

对于严格递增但缓慢的数组，例如`[1, 2, 3, 4, 5, 6]`，窗口总和逐渐增长，并且二分搜索清楚地识别了转变点，因为单调属性在所有索引中都毫无例外地成立。
