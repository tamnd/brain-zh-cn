 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 的数字排列。 从这个排列中，我们考虑每个连续的段并计算其 MEX，即未出现在该段内的最小正整数。 任务是在排列的所有可能段上求和该 MEX 值。 

关键结构是我们不使用任意数组。 从 1 到 n 的每个值都只出现一次，这使得值 1 到 k 的存在条件更容易跟踪，因为它们每个都对应于数组中的单个位置。 

如果 n 很大，大约为 200,000 或更多，则枚举所有子数组并计算每个子数组的 MEX 是立即不可行的。 子数组的数量为 O(n^2)，甚至每个子数组的线性扫描也会将其推至 O(n^3)，这远远超出了典型的限制。 这迫使我们根据价值的贡献而不是直接列举来重新表述问题。 

当数组较小或早期值聚集时，会出现微妙的边缘情况。 例如，如果排列为 [1, 2, 3]，则每个子数组仅在初始段为空时才具有较大的 MEX，并且关于局部间隙的幼稚推理很容易错过全局覆盖。 另一个极端情况是反向排列，例如 [n, n−1, ..., 1]，其中小数字的位置相距很远，从而最大化包含前缀所需的范围。 

一种幼稚的方法会独立地为每个子数组重复重新计算 MEX，尽管逻辑上是正确的，但由于时间复杂性，这种方法会默默地失败。 

## 方法

 蛮力策略很简单。 对于每个子数组，我们扫描其元素，标记出现的值，并计算最小的缺失整数。 这是可行的，因为 MEX 是在每个子数组本地定义的，从概念上来说不需要更多。 问题是每个子数组的处理成本为 O(n)，并且有 O(n^2) 个子数组，总共需要 O(n^3) 次操作，这对于大输入来说太慢了。 

为了改善这一点，我们翻转视角。 我们不是问“这个子数组的 MEX 是什么”，而是问“哪些子数组的 MEX 至少为 k + 1”。 当且仅当子数组包含从 1 到 k 的每个数字时，子数组的 MEX 大于 k。 因为我们正在处理排列，所以每个数字只出现一次，因此条件“包含所有 1..k”变成了一个简单的区间条件。 

对于每个 k，我们找到数字 1 到 k 的位置。 令 L_k 为这些位置中的最小值，R_k 为最大值。 任何包含所有 1..k 的子数组必须完全覆盖此区间 [L_k, R_k]。 此类子数组的数量为左端点​​的 L_k 个选择和右端点的 (n − R_k + 1) 个选择。 

这将问题转化为随着 k 的增加，维持由 1..k 的位置形成的扩展区间。 每个步骤仅更新间隔端点，并且在每 k 的恒定时间内计算贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) | O(n^3) | O(n) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

1. 构建一个数组 pos，使得 pos[x] 是排列中值 x 的索引。 这允许恒定时间访问每个数字出现的位置。 
2. 维护两个变量 L 和 R，代表随着 k 的增加，值 1 到 k 中的最小和最大位置。 最初 L = R = pos[1]，因为仅包含值 1。 
3. 对于从 1 到 n 的每个 k，通过更新 L = min(L, pos[k]) 和 R = max(R, pos[k]) 来扩展间隔。 这确保 L 和 R 始终描述覆盖所有值 1..k 的最小线段。 
4. 对于每个 k，计算有多少个子数组包含整个区间 [L, R]。 左端点可以以 L 种方式选择，因为它必须在 L 处或之前开始。右端点可以以 (n − R + 1) 种方式选择，因为它必须在 R 处或之后结束。将它们相乘即可得到 count_k。 
5. 累加答案+=count_k。 该值表示 MEX 严格大于 k 的子数组的数量。 
6.处理完所有k后，返回最终的累加值。 这是可行的，因为每个子数组对于每小于其 MEX 的 k 贡献恰好 1。 

### 为什么它有效

 每个子数组对每个整数 k 贡献一次最终总和，使得 1..k 完全包含在其中。 该条件相当于子数组覆盖由 1..k 的位置定义的区间。 由于排列结构保证每个值前缀都有一个区间，因此对覆盖此区间的子数组进行计数就等于对所有 MEX 大于 k 的子数组进行了计数。 对 k 求和可重构 MEX 总和，而不会重叠或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(a):
        pos[v] = i

    L = pos[1]
    R = pos[1]
    ans = 0

    for k in range(1, n + 1):
        L = min(L, pos[k])
        R = max(R, pos[k])
        ans += (L + 1) * (n - R)

    print(ans)

if __name__ == "__main__":
    solve()
```核心实现依赖于预计算位置，因此间隔更新是恒定时间。 表达式`(L + 1) * (n - R)`假设从 0 开始索引，其中`L + 1`计算有效的左端点和`n - R`严格计算 R 右侧的有效右端点。这里错误的主要来源是逐一索引：将端点视为包含或排除不一致会完全改变公式。 

该循环逐渐增大间隔，并且除了位置数组之外不需要其他数据结构。

 ## 边缘情况

 ### 单个元素

 输入：```
1
1
```这里 L = R = 0。唯一的子数组是整个数组，并且每个前缀条件立即成立。 该公式给出 (L+1)(n−R) = 1，它与唯一的 MEX 值匹配。 

### 完全反转排列

 输入：```
4
4 3 2 1
```L和R逐步向内扩展，直至覆盖整个阵列。 早期的 k 值会产生较大的间隔，从而快速减少子数组的数量。 该算法正确地跟踪这一点，因为它始终使用全局最小和最大位置，而不是邻接。 

### 随机洗牌边缘行为

 对于分散的小值的输入，L 和 R 波动显着。 该算法仍然保持正确，因为每次更新仅取决于极值，中间结构与区间覆盖无关。
