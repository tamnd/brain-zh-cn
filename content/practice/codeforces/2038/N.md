 ## 解决方案
 ## 问题理解

 我们给出了一个非常小的固定长度三的表达式。 第一个和最后一个字符是数字，中间的字符是比较运算符：小于、等于或大于。 我们的任务是将该表达式修改为正确的数学语句，同时更改尽可能少的字符。 

正确的表述意味着两个数字之间的关系必须与运算符匹配。 如果左边的数字小于右边的数字，则运算符必须是“<”。 如果相等，则运算符必须是“=”。 如果左边的数字较大，则运算符必须是“>”。 

每个测试用例都是独立的，我们为每个测试用例输出一个有效的校正表达式，从而最大限度地减少字符编辑的数量。 

因为每个字符串都有恒定的大小，所以约束非常小。 即使是尝试数字和运算符的所有可能性的强力方法也足够快，因为每个数字只有 10 个选择，而运算符只有 3 个选择。 这为每个测试用例提供了 300 个组合的固定搜索空间，最多 300 个测试用例，这是微不足道的。 

这个问题的唯一微妙之处在于，更改数字或运算符都同样算作每个字符的一次修改。 这意味着我们正在最小化到任何有效表达式的汉明距离。 

一个幼稚的错误是只修复运算符而保持数字不变，反之亦然。 如果更改一位数字而不是运算符会产生较少的总更改，则这种方法会失败。 例如，转动`5<3`进入`5>3`改变一个字符（运算符），但将其变成`0<3`也需要进行一次更改（仅数字），因此必须在全球范围内考虑和比较两者。 

## 方法

 暴力解决方案会尝试所有可能的有效表达式并测量有多少位置与输入不同。 对于每个测试用例，我们枚举从 0 到 9 的所有数字对以及所有三个比较运算符。 对于每个候选表达式，我们检查它在逻辑上是否有效，然后通过计算不匹配的字符来计算它与输入字符串的距离。 最佳候选人被选中。 

这是可行的，因为整个搜索空间很小并且与输入大小完全无关。 然而，即使这样也是不必要的，因为问题的结构允许直接推理。 

关键的观察结果是有效性仅取决于两个数字的相对顺序。 这会将所有有效表达式分为三组：左小于右、等于或大于。 对于每个组，我们可以通过选择最小化原始端点变化的数字并将它们与正确的运算符配对来计算最佳代表。 

我们不是搜索所有可能性，而是评估三个逻辑结果并选择需要最少编辑的一个。 由于数字是独立的，因此每个类别中的最佳选择就是保留原始数字，除非我们故意需要调整它们，但调整数字仅当它比修复运算符更便宜地帮助匹配不同的比较类别时才有用。 

实际上，由于字符串长度为三，我们可以通过选择每种情况的最佳数字对来直接计算三种情况的成本。

 ## 算法演练

 我们独立对待每个测试用例。 

1. 解析左边的数字、运算符和右边的数字。 我们将它们保留为整数以便于比较。 这为我们提供了基线表达式及其当前的正确性。 
2. 计算使表达式满足“<”的成本。 为此，我们需要任何一对数字，其中左侧数字严格小于右侧数字。 最便宜的方法是尽可能保持数字不变，但只允许有效的数字对。 因此，我们考虑所有数字对 (a, b)，使得 a < b 并计算需要多少次更改才能将原始端点转换为 (a, b) 并将运算符转换为“<”。 所有这些对中的最小值是强制正确的“<”表达式的成本。 
3. 计算“=”的相同成本，仅考虑 a = b 的对，并强制运算符为“=”。 
4. 计算“>”的相同成本，考虑 a > b 的对并强制执行运算符。 

每个候选成本衡量必须更改多少位置才能达到该类别中的有效表达式。 

1. 选择成本最小的类别。 如果有多个领带，任何一个都可以接受。 
2. 通过记住哪个候选产生最小成本来重建实际的最佳表达式。 

### 为什么它有效

 该算法根据比较关系将所有有效表达式划分为三个不相交的集合。 在每个集合中，我们明确评估每个可能的数字对，因此我们不会错过任何配置。 由于每个有效表达式都属于这些集合之一，因此全局最小值必须出现在计算的候选者之一中。 成本函数正是字符替换的数量，因此最小化所有有效表达式相当于最小化这三个详尽类别。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(s):
    a0 = int(s[0])
    op0 = s[1]
    b0 = int(s[2])

    best_cost = 10
    best_expr = s

    ops = ['<', '=', '>']

    for op in ops:
        for a in range(10):
            for b in range(10):
                if op == '<' and not (a < b):
                    continue
                if op == '=' and not (a == b):
                    continue
                if op == '>' and not (a > b):
                    continue

                cost = 0
                if a != a0:
                    cost += 1
                if b != b0:
                    cost += 1
                if op != op0:
                    cost += 1

                if cost < best_cost:
                    best_cost = cost
                    best_expr = str(a) + op + str(b)

    return best_expr

def main():
    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        out.append(solve_case(s))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```该解决方案直接实现了前面描述的穷举但有界的搜索。 嵌套循环迭代所有数字对和所有运算符。 对于每个候选者，我们首先过滤无效组合，因此我们只考虑逻辑上正确的表达式。 然后我们根据输入字符串位置逐个位置计算编辑距离。 只要找到成本较低的配置，就会存储并更新最佳候选配置。 

由于每个测试用例的搜索空间是恒定的，因此可以在限制内轻松运行。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        s = input().strip()
        a0, op0, b0 = int(s[0]), s[1], int(s[2])

        best = 10
        ans = s

        for op in "<=>":
            for a in range(10):
                for b in range(10):
                    if op == "<" and not (a < b):
                        continue
                    if op == "=" and not (a == b):
                        continue

                    if cost < best:
                        best = cost
                        ans = f"{a}{op}{b}"

        return ans

    t = int(input())
    return "\n".join(solve() for _ in range(t))

 ## 边缘情况

 最重要的边缘情况是表达式已经正确的情况。 对于像这样的输入`0=0`，该算法在所有相等候选者中对其进行评估，并立即找到零成本解决方案，因此它返回原始字符串而不进行修改。 

当两个数字相等但运算符不相等时会出现另一种边缘情况，例如`4<4`。 该算法考虑所有有效的相等对，并发现单独更改运算符比更改任一数字更便宜，从而产生`4=4`。 

第三种情况是数字和运算符完全不一致，比如`7<3`。 这里的最佳解决方案可能是翻转运算符或根据成本调整一位数。 枚举确保两者都被考虑，因此它总是选择最小编辑更正，例如`3<7`或者`7>3`，既有效又同样最优。
