 ## 解决方案
 ## 问题理解

 我们被要求通过一个$n \times n$从左上角到右下角的网格，仅向右或向下步进。 每个细胞$(i, j)$通过最大公约数贡献仅取决于其行索引和列索引的成本：$\gcd(i, a) + \gcd(j, b)$。 路径的总成本是所有访问过的单元（包括两个端点）的总和。 

运动结构是一个单调路径问题。 任何有效的路线都是通过选择我们向右走的地方和向下走的地方来完全确定的，并且每条这样的路径都精确地访问$2n-1$细胞。 困难在于行和列的成本并不统一，但算术结构与除数相关$a$和$b$。 

约束条件允许$n$最多$10^6$，这会立即排除网格上的任何每单元动态编程。 一个直截了当的$O(n^2)$无论是在时间上还是在内存上，网格的遍历都是不可能的。 甚至$O(n \log n)$如果应用于所有单元格，每个单元格的推理将会太大。 

一个微妙的方面是成本完全分为行部分和列部分。 路径的贡献为$$\sum \gcd(i, a) \;+\; \sum \gcd(j, b)$$但指数$i$和$j$不是独立的，因为路径选择每行和每列被访问的次数。 关键的困难是了解每行和每列在任何单调路径上贡献了多少次。 

一种简单的方法是尝试计算 DAG 中的最短路径$n^2$节点，但这立即不可行。 另一个不正确的捷径是假设我们可以分别最小化行和列的贡献，但这是失败的，因为路径结构耦合了行和列的遍历方式。 

## 方法

 暴力视图将网格视为有向无环图，其中每个单元格都有两个传出边缘。 在所有单元上运行 DP 将计算$$dp[i][j] = c(i, j) + \min(dp[i+1][j], dp[i][j+1])$$这在原则上是正确的，但需要$O(n^2)$状态，这是不可能的$n = 10^6$。 即使存储网格也会消耗太多内存。 

关键的结构观察是成本函数附加地分为行相关部分和列相关部分。 这使我们能够将问题分成两个独立的一维问题，但前提是要了解每行和每列被访问了多少次。 

在任意单调路径中$(1,1)$到$(n,n)$, 每行$i$只输入一次并对路径成本贡献一次，因为我们输入 row 的那一刻$i$，我们最终必须离开它，再也不会回来。 对于每一列也是如此。 因此，每条路径恰好包含每个行索引的一次出现以及每个列索引的恰好一次出现。 

这将问题简化为计算：$$\sum_{i=1}^{n} \gcd(i, a) \;+\; \sum_{j=1}^{n} \gcd(j, b)$$然而，这还不够，因为起始单元格$(1,1)$同时贡献行和列部分，我们必须确保不会错误地重复计算。 仔细分解表明总成本恰好是：$$\left(\sum_{i=1}^{n} \gcd(i, a)\right) + \left(\sum_{j=1}^{n} \gcd(j, b)\right)$$这与所选路径无关，这意味着每条有效路径都具有相同的成本。 然后，问题就简化为有效地计算两个类似除数和的函数。 

计算$\sum_{i=1}^{n} \gcd(i, a)$，我们根据索引的 gcd 值对索引进行分组。 对于每个除数$d$的$a$，我们计算有多少个整数$[1, n]$正好有gcd$d$和$a$。 使用标准数论，这变成：$$\sum_{d \mid a} d \cdot \varphi\left(\frac{a}{d}\right) \cdot \left\lfloor \frac{n}{d} \right\rfloor$$更直接和更简单的方法是迭代除数并通过欧拉的 totient 贡献使用包含排除，或者预先计算每个除数的 gcd 贡献$a$和$b$。 自从$a, b \le 10^6$，我们可以枚举除数$O(\sqrt{a})$和总贡献$O(\sqrt{a} + \sqrt{b})$。

 ## 算法演练

 1. 观察成本分为独立的行和列贡献。 这是有效的，因为$\gcd(i,a)$仅取决于$i$， 和$\gcd(j,b)$仅取决于$j$，因此没有路径选择可以以非加性方式将它们耦合。 
2. 计算$S_a = \sum_{i=1}^{n} \gcd(i, a)$。 而不是迭代所有$i$, 枚举除数$d$的$a$。 每个除数代表一个潜在的 gcd 值结构，其倍数为$d$。 除数的贡献取决于除数的倍数的频率$d$出现在$[1,n]$。 
3. 对于每个除数$d$的$a$，计算中有多少个数字$[1,n]$可以被整除$d$，即$\lfloor n/d \rfloor$。 这些通过对除数的包含-排除来贡献$a$，分离精确的 gcd 层。 
4. 重复相同的计算$S_b = \sum_{j=1}^{n} \gcd(j, b)$。 
5. 返回$S_a + S_b$。 

### 为什么它有效

 正确性取决于以下事实：网格路径结构强制执行每行索引精确一次访问和每列索引精确一次访问，无论向右和向下移动如何排列。 这消除了对交错选择的任何依赖。 一旦建立，成本就变成了独立索引集上的纯加法算术函数，可以在不模拟网格的情况下进行评估。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def sum_gcd(n, x):
    # compute sum_{i=1..n} gcd(i, x)
    res = 0
    d = 1
    while d * d <= x:
        if x % d == 0:
            d1 = d
            d2 = x // d

            # for divisor d1
            cnt = n // d1
            if cnt:
                res += d1 * cnt

            # for divisor d2
            if d2 != d1:
                cnt = n // d2
                if cnt:
                    res += d2 * cnt
        d += 1
    return res

def main():
    n, a, b = map(int, input().split())
    print(sum_gcd(n, a) + sum_gcd(n, b))

if __name__ == "__main__":
    main()
```该实现依赖于枚举除数$a$和$b$。 对于每个除数$d$，我们根据多少个指数来累积其贡献$n$可以被整除$d$。 关键的实现细节是避免网格上的任何每单元迭代，这是不可行的。 

循环结构确保每个除数被处理一次，并且平方根界限即使在最大输入大小下也能保持计算效率。

 ## 边缘情况

 最小网格，例如$n = 2$公开实现是否正确计算两个端点。 在这种情况下，每条路径都是强制的，因此任何差异都会立即表明对开始或结束贡献的处理不正确。 

什么时候$a = 1$或者$b = 1$，所有 gcd 项都崩溃为 1，结果变成纯粹的结构性的。 该算法正确归约，因为每个除数枚举仅包含平凡除数 1，并且总和恰好变为$n$每个维度。 

大素值$a$或者$b$确保除数循环仅运行两次。 这证实了该算法不依赖于密集除数结构，并且在最坏情况的算术场景中保持稳定。
