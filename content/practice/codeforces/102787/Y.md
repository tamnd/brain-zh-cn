 ## 解决方案
 ## 问题理解

 该问题追踪一排喷嚏，其中每个喷嚏都有零颗或一颗星星。 查询选择一个连续的间隔，并通过一台机器发送这些喷嚏，该机器会切换它们的值：零变成一，一变成零。 每次切换操作后，我们必须报告所有喷嚏都具有相同值的最长连续段的长度。 问题的第一个版本仅包含这些切换查询。 

输入给出描述喷嚏的初始二进制字符串，然后给出要切换的间隔序列。 对于每个间隔，输出不是 1 或 0 的数量，而是当前字符串中任意位置的相同相邻值的最长块。 

约束条件大：喷嚏次数和操作次数都可以达到$3 \cdot 10^5$。 在每次操作后扫描整个数组的解决方案将执行大约$9 \cdot 10^{10}$最坏情况下的操作，远远超出了正常比赛的时间限制。 我们需要在对数时间内处理每个更新和查询结果。 

主要的边缘情况来自接触边界或包含整个数组的间隔。 仅在间隔内更新但忘记答案可能跨边界合并的解决方案将会失败。 例如，如果输入是：```
5 1
00111
1 2 4
```数组变成`01011`，所以答案是`2`因为最后两个形成最长的相等线段。 一个粗心的实现，只检查翻转的段`101`可能会错误报告`1`。 

另一个棘手的情况是翻转已经统一的区间。 例如：```
4 1
0000
1 2 3
```结果是`0110`，答案是`2`。 更新将中间部分从全零更改为全一，但外部零保持连接。 仅存储在更改的间隔内创建的最大段的方法可能会错过外部贡献。 

最终的边界情况是单个元素更新：```
3 1
010
1 2 2
```数组变成`000`，所以答案是`3`。 任何假设翻转间隔总是有两侧要合并的实现都可能会错误地处理这种情况。 

## 方法

 直接的解决方案是存储二进制数组并通过从`l`到`r`，切换每个元素。 更新后，另一次扫描可以找到最长的相等值。 这是正确的，因为它准确地模拟了问题所描述的过程。 然而，一次操作就可以触及所有$n$元素，而找到答案也需要成本$O(n)$。 和$q$操作，最坏的情况变成$O(nq)$，这大约是$9 \cdot 10^{10}$最大约束的元素访问。 

关键的观察是该操作是范围翻转，并且请求的答案是可以从相邻段组合的属性。 线段树可以通过存储足够的信息来合并两半来表示每个区间。 我们不需要每次操作后整个段的精确值。 我们只需要最长的前缀、最长的后缀、最长的零和一内部串，以及段长度。 

当一个段被翻转时，零和一只是交换角色。 最长的零前缀将成为之前最长的一前缀，后缀和最佳段也是如此。 这使得惰性传播变得自然：我们不是访问每个元素，而是将整个段标记为翻转，并延迟推送该更改，直到真正需要子元素为止。 

蛮力之所以有效，是因为每个元素都被显式更改。 它会失败，因为太多元素可能会被频繁更改。 线段树之所以有效，是因为大范围更新可以由单个惰性标志表示，从而将每个操作减少到$O(\log n)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nq)$|$O(n)$| 太慢了 |
 | 最佳 |$O(q \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 从初始二进制字符串构建线段树。 对于每个节点，存储段长度、仅由零组成的最长前缀和后缀、相同的 1 值、最佳全零段、最佳全一段以及延迟翻转标志。 

这些值正是合并两个相邻段所需的信息。 任何涉及两个子级之间边界的答案都必须使用左子级的后缀和右子级的前缀。 
2. 对于一个查询间隔$[l,r]$，递归访问线段树。 如果某个节点完全位于该区间内，则对该节点应用翻转，而不是深入该节点。 

应用翻转仅将每个零相关字段与其相应的一相关字段交换并切换惰性标志。 该段的长度不会改变。 
3. 当访问部分覆盖的节点时，将其待翻转的节点推送到其子节点，然后再继续。 

这使孩子与父母的当前状态保持一致。 延迟更新是安全的，因为父级已经包含正确的组合信息。 
4.更新间隔后，读取根节点的答案作为其最长全0段和最长全1段中的最大值。 

根代表完整的数组，因此其存储的最佳段正是所需的答案。 

为什么它有效：

 每个线段树节点总是描述其区间的当前状态。 合并操作保留了此属性，因为每个最长的等值段要么完全位于左子节点中，要么完全位于右子节点中，要么跨越中间边界。 存储的前缀和后缀值处理交叉情况。 翻转仅交换零和一的角色，因此交换存储的零和一信息可以保持节点正确。 由于每次更新都会保留所有受影响节点的不变量，因此根始终包含正确的最长均匀段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = (
        "length",
        "pref0", "suff0", "best0",
        "pref1", "suff1", "best1",
        "lazy"
    )

    def __init__(self):
        self.length = 0
        self.pref0 = self.suff0 = self.best0 = 0
        self.pref1 = self.suff1 = self.best1 = 0
        self.lazy = False

def merge(a, b):
    c = Node()
    c.length = a.length + b.length

    c.pref0 = a.pref0
    if a.pref0 == a.length:
        c.pref0 += b.pref0

    c.pref1 = a.pref1
    if a.pref1 == a.length:
        c.pref1 += b.pref1

    c.suff0 = b.suff0
    if b.suff0 == b.length:
        c.suff0 += a.suff0

    c.suff1 = b.suff1
    if b.suff1 == b.length:
        c.suff1 += a.suff1

    c.best0 = max(a.best0, b.best0, a.suff0 + b.pref0)
    c.best1 = max(a.best1, b.best1, a.suff1 + b.pref1)

    return c

def apply_flip(node):
    node.pref0, node.pref1 = node.pref1, node.pref0
    node.suff0, node.suff1 = node.suff1, node.suff0
    node.best0, node.best1 = node.best1, node.best0
    node.lazy = not node.lazy

def build(idx, l, r):
    tree[idx] = Node()
    if l == r:
        tree[idx].length = 1
        if s[l] == '0':
            tree[idx].pref0 = tree[idx].suff0 = tree[idx].best0 = 1
        else:
            tree[idx].pref1 = tree[idx].suff1 = tree[idx].best1 = 1
        return

    m = (l + r) // 2
    build(idx * 2, l, m)
    build(idx * 2 + 1, m + 1, r)
    tree[idx] = merge(tree[idx * 2], tree[idx * 2 + 1])

def push(idx):
    if tree[idx].lazy:
        apply_flip(tree[idx * 2])
        apply_flip(tree[idx * 2 + 1])
        tree[idx].lazy = False

def update(idx, l, r, ql, qr):
    if qr < l or r < ql:
        return
    if ql <= l and r <= qr:
        apply_flip(tree[idx])
        return

    push(idx)
    m = (l + r) // 2
    update(idx * 2, l, m, ql, qr)
    update(idx * 2 + 1, m + 1, r, ql, qr)
    tree[idx] = merge(tree[idx * 2], tree[idx * 2 + 1])

def solve():
    global s, tree

    n, q = map(int, input().split())
    s = input().strip()
    s = " " + s

    tree = [None] * (4 * n + 5)
    build(1, 1, n)

    ans = []
    for _ in range(q):
        _, l, r = map(int, input().split())
        update(1, 1, n, l, r)
        ans.append(str(max(tree[1].best0, tree[1].best1)))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```这`Node`对象仅存储合并所需的信息。 为零游程和一游程保留单独的值可以避免需要了解段的实际内容。 

这`merge`函数处理最佳段的三个可能位置：完全在左孩子中、完全在右孩子中或跨越边界。 交叉情况是存储后缀和前缀长度的原因。 

这`apply_flip`函数是观察问题的核心。 翻转永远不会改变段长度，它只会交换零和一的含义。 惰性标志记录孩子们仍然需要应用此交换。 

递归更新使用惰性传播。 完全覆盖的段会立即翻转，而部分段会先向下推。 这种排序可以防止过时的子信息影响未来的合并。 

Python 整数在这里不会溢出，因为最大的存储值只有$n$，这最多是$3 \cdot 10^5$。 索引在位置零处使用虚拟字符，以便查询索引直接与语句匹配。

import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().split()
    sys.stdin = old_stdin

    it = iter(data)
    n = int(next(it))
    q = int(next(it))
    s = next(it)

    arr = list(map(int, s))
    out = []

    for _ in range(q):
        next(it)
        l = int(next(it)) - 1
        r = int(next(it)) - 1
        for i in range(l, r + 1):

            if arr[i] == arr[i - 1]:
                cur += 1
            else:
                cur = 1
            best = max(best, cur)

    return "\n".join(out)

 ## 边缘情况

 对于第一个边界示例：```
5 1
00111
1 2 4
```树翻转位置二到四。 左边部分变化自`0`到`1`，中间部分由`0,1,1`到`1,0,0`，剩下的就是右边的部分`1`。 最终的字符串是`01011`，其中最长的相等线段的长度`2`。 合并操作发现这一点是因为它将来自一个子项的后缀信息与来自下一个子项的前缀信息组合在一起。 

对于统一段示例：```
4 1
0000
1 2 3
```中间部分接受惰性翻转并变成 1。 仅当线段树组合了正确的相邻信息时，两个外部零才保持连接。 存储的前缀、后缀和最佳值允许根返回`2`。 

对于单元素更新：```
3 1
010
1 2 2
```位置二处的叶子从 1 翻转到 0。 父节点向上合并，产生`000`。 根报告完整长度`3`，表明单位置范围与较大间隔的工作方式相同。
