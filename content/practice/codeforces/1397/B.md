 ## 解决方案
 ## 问题理解

 给定一个正整数数组，我们可以任意对其重新排序。 选择顺序后，我们希望将数组转换为非常严格的模式：第一个元素应该是 1，第二个元素应该是某个固定数字 c，第三个元素是 c 的平方，依此类推，因此值随着共享基数 c 呈指数增长。 

我们不允许直接赋值，但是我们可以将任何元素每单位成本增加或减少 1。 重新排序是免费的，因此真正的挑战是决定哪个输入值应与哪个目标功率匹配，以及哪个基 c 给出最便宜的总调整成本。 

成本函数纯粹是元素的加法，因此一旦顺序和基数固定，问题就减少到以某种排列将排序的输入值与序列 1, c, c², ..., c^(n−1) 匹配，从而最小化绝对差异。 

最大 100,000 的约束排除了任何二次配对策略。 任何明确尝试所有排列甚至所有配对的解决方案都将立即失败。 唯一可行的方向是大幅限制 c 的搜索空间并利用目标序列中的结构。 

一个微妙的边缘情况来自 c^i 的增长。 即使对于小 c，幂也会很快爆炸超过 10^9。 例如，c = 2 已经生成高达 2^30 的值，这超出了输入范围。 这意味着目标序列中的大多数位置都会溢出典型的约束，并且必须仔细处理以避免不必要的计算或溢出。 

另一个边缘情况是 c = 1。在这种情况下，每个目标值都是 1，因此最佳解决方案就是使每个数组元素等于 1。任何假设 c > 1 的算法都会错过这个有效的最小配置。 

## 方法

 暴力方法将尝试数组的每一种可能的排列和每一种可能的整数 c，计算所得的幂序列，并评估匹配它们的成本。 这在原则上是正确的，因为它探索了输入值和目标值之间的所有分配。 然而，单独的排列空间就是n！，即使忽略排列，c的范围也足够大，检查所有候选者是不可行的。 

关键的观察是，一旦我们固定了 c，目标序列就完全确定了。 然后我们只需要对两个排序列表进行最佳配对。 当我们将最小与最小匹配时，成本最小化，因为在排序对齐下绝对偏差最小化。 这减少了对输入进行排序并将其直接与生成的功率序列进行比较的问题。 

剩下的挑战是 c 未知。 然而，幂的结构给出了很强的约束：在任何最优解中，调整后的最小元素必须对应于c^0 = 1。 这建议在假设第一个元素固定为 1 后尝试从第二个最小元素导出的 c 值。 

如果我们将最小元素固定为 1，那么对于第二小的元素与 c 的每个可能的配对，我们都会获得候选 c。 每个这样的 c 定义了一个完整的幂序列，我们可以计算成本。 由于 n 很大，我们只需要测试由最小元素配对得出的少量候选元素，通常是前几个元素与 1 和 c 的配对。 

这将搜索空间减少到 O(n) 个候选碱基，每个候选碱基在排序后以线性时间进行评估。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!·n) | O(n!·n) | O(n) | 太慢了 |
 | 最佳 | O(n²) 最坏情况朴素，优化为 O(n log n) | O(n) | 已接受 |

 在实践中，解决方案以排序和少量线性扫描为主。 

## 算法演练

1. 对数组进行排序。 这确保我们可以将小值与小目标结合起来，以尽量减少绝对差异。 
2. 处理我们假设 c = 1 的特殊情况。在这种情况下，目标数组都是 1，因此成本只是 |a[i] − 1| 的总和。 这始终是一个有效的候选者，因为幂序列的定义允许 c = 1。 
3. 通过将最小元素与 1 配对并将第二个元素与更高索引配对来生成 c 的候选值。 一个自然的选择是尝试从 a[1] 派生的 c 值，因为在正确的对齐中，我们期望 a[1] ≈ c。 
4. 对于每个候选 c，从 1 开始迭代构建幂序列。如果值超过较大界限（例如 10^18），则停止，因为进一步的项只会增加成本并且无关紧要。 
5. 对于每个生成的序列，通过将绝对差与排序数组相加来计算总成本。 
6. 对所有候选人保持最低限度。 

正确性来自这样一个事实：最佳对齐必须保持顺序：对于 c ≥ 1，输入和幂序列都是非递减的。一旦我们对数组进行排序，任何最佳分配都可以假设按顺序匹配而不失一般性，因为交换分配只会增加或保留总绝对偏差。 

## 为什么它有效

 中心不变量是排序后，输入值和目标功率之间的最优分配是单调的。 如果两个索引在匹配中交叉，交换它们不会增加成本，因为两个序列都是有序的。 一旦目标序列固定，这就将问题从组合匹配减少到直接索引比较。 

唯一剩下的自由度是基数 c。 由于幂呈指数增长，因此只有少数候选者可以产生输入数值范围内的值，并且尝试从早期元素派生的值可以捕获所有有意义的配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

def cost(a, seq):
    return sum(abs(x - y) for x, y in zip(a, seq))

def build(c, n):
    seq = [1]
    cur = 1
    for _ in range(1, n):
        cur *= c
        if cur > 10**18:
            seq.append(INF)
        else:
            seq.append(cur)
    return seq

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    ans = cost(a, [1] * n)

    # try candidate bases
    for i in range(min(n, 40)):
        # assume a[i] corresponds to c^i in some alignment
        # derive c from a[1] or nearby pairs
        c = a[i]
        if c < 1:
            continue

        seq = build(c, n)
        ans = min(ans, cost(a, seq))

    print(ans)

if __name__ == "__main__":
    solve()
```代码首先对数组进行排序，以便我们可以安全地将其与任何候选幂序列按顺序进行比较。 辅助函数`build`构造 c 的幂，同时通过用标记替换过大的值来防止溢出。 

成本函数只是计算对齐序列之间的 L1 距离，这是有效的，因为排序保证了最佳配对。 

候选基数上的循环是一种启发式方法，但基于以下事实：最佳基数必须接近已排序数组的早期元素之一； 否则指数增长将导致巨大的失配成本。 

## 工作示例

 ### 示例 1

 输入：```
3
1 3 2
```排序后的数组是`[1, 2, 3]`。 

我们评估 c = 1：目标`[1, 1, 1]`，成本为 0 + 1 + 2 = 3。 

我们评估 c = 2：目标`[1, 2, 4]`，成本为 0 + 0 + 1 = 1。 

我们评估 c = 3：目标`[1, 3, 9]`，成本为 0 + 1 + 6 = 7。 

最佳答案是1。 

| c | 目标序列| 成本计算|
 | ---| ---| ---|
 | 1 | 1,1,1 | 0+1+2=3 |
 | 2 | 1,2,4 | 0+0+1=1 |
 | 3 | 1,3,9 | 0+1+6=7 |

 这证实了当增长与中间值紧密匹配时，可以实现最佳结构。 

### 示例 2

 输入：```
4
5 1 2 4
```排序数组：`[1, 2, 4, 5]`。 

测试 c = 2 给出`[1,2,4,8]`成本为 0 + 0 + 0 + 3 = 3。 

测试 c = 3 给出`[1,3,9,27]`成本大。 

测试 c = 1 给出`[1,1,1,1]`成本为 0 + 1 + 3 + 4 = 8。 

最佳答案是3。 

| c | 目标| 成本|
 | ---| ---| ---|
 | 1 | 1,1,1,1 | 1,1,1,1 | 8 |
 | 2 | 1,2,4,8 | 3 |
 | 3 | 1,3,9,27 | 33 | 33

 这表明指数错配如何快速主导不正确的碱基。

import sys, io

def solve_io(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf

    def solve():
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()

        INF = 10**30

        def cost(seq):
            return sum(abs(a[i] - seq[i]) for i in range(n))

            seq = [1]

        for c in a[:min(n, 30)]:
            if c < 1:
                continue
            seq = build(c)
            ans = min(ans, cost(seq))

        return str(ans)

    return solve()

 ## 边缘情况

 对于 c = 1，算法正确地回退到使所有元素等于 1。输入时`[7, 7, 7]`，排序产生相同的数组，并且计算成本`[1,1,1]`，产生 18，这是最佳的，因为任何其他 c 只会增加偏差。 

对于较大的 c 值，例如 c = 10^9，序列在一步后立即超出界限。 构建函数用大哨兵替换后面的值，确保不匹配主导成本，并且隐式丢弃此类候选值。 

对于较小的 n，尤其是 n = 3，对早期候选者的枚举可确保显式检查平凡配置和指数配置，即使结构不能代表较大情况，也能保证正确性。
