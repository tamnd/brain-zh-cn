 ## 解决方案
 ## 问题理解

 备忘单具有以字符为单位的固定容量。 Setsuna 有一组关键字，但重复的关键字只重要一次，因为最终的工作表不能包含重复项。 如果在工作表上放置多个关键字，则它们在相邻单词之间需要一个空格，因此总占用长度是所选关键字长度的总和加上两个所选关键字之间的每个连接的分隔符。 

任务是选择尽可能多的不同关键字，且其总书写长度不超过可用空间。 

关键字数量最多为 1000 个，每个关键字长度最多为 100。这意味着输入对于排序和线性扫描来说足够小，但不适合尝试每个子集。 1000个不同的关键词，可能的选择数量是2^1000，这远远超出了时间限制所能探索的范围。 

有几个细节可能会导致错误的答案。 重复的单词不得计算两次。 例如：```
n = 10, m = 3
hello hello hi
```正确答案是 2，因为可用的单词只有`hello`和`hi`。 A careless implementation that processes every input word separately might count three possible keywords.

 单词之间的空格也会影响答案。 例如：```
n = 7, m = 2
abc defg
```正确答案是 1。这两个单词加在一起需要 3 + 1 + 4 = 8 个字符，因此它们不能同时容纳。 一种仅比较字长总和的实现`n`会错误地返回 2。 

大写和小写字母的顺序很重要。 例如：```
n = 5, m = 2
A a
```正确答案是 2，因为这些是不同的关键字，并且它们恰好适合一个空格：1 + 1 + 1 = 3 个字符。 

## 方法

 直接的解决方案将考虑每个可能的关键字组，删除组内的重复项，计算其总长度，并保留适合的最大组。 这种方法是正确的，因为它会检查每个可能的答案。 然而，子集的数量呈指数增长。 即使只有 60 个关键字，也可能有超过 10^18 个可能的子集，使得该策略无法使用。 

关键的观察结果是，除了长度之外，每个关键字都具有相同的成本结构。 如果我们决定把`k`备忘单上的关键字，空格的贡献完全一样`k - 1`人物。 目标不是最大化所使用的总长度，而是最大化所选关键字的数量。 由于每个选定的关键字对答案的贡献恰好为 1，因此最好的选择始终是将可用空间花在最短的关键字上。 

删除重复项后，将剩余的关键字按长度排序。 从最短到最长的顺序取关键词可以得到最大可能的数量。 如果某个较长的关键字可以容纳，则用它替换任何选定的较短关键字不会增加选定单词的数量，只会消耗更多空间。 这种贪婪的排序捕获了所有有用的选择，而无需尝试组合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^m * m) | O(2^m * m) | O(米) | 太慢了|
 | 最佳| O(m log m) | O(米) | 已接受 |

 ## 算法演练

 1. 读取所有关键字并将它们插入到集合中。 该集合会删除重复的关键字，因为多次写入相同的关键字是不允许的，并且永远不会增加答案。 
2. 将不同的关键字转换为列表，并按长度升序排列。 较短的关键字是首选，因为每个选定的关键字具有相同的值，但较短的关键字占用的空间较少。 
3. 保留一个代表当前使用的字符数的变量和另一个代表所选关键字数量的变量。 最初两个值都为零。 
4. 迭代排序后的关键字。 对于当前关键字，计算所需的额外空间。 如果尚未选择关键字，则成本仅是其长度。 否则，成本是其长度加一，因为需要分隔空间。 
5. 如果新总数仍符合备忘单限制，则添加关键字。 增加所选计数并继续。 如果关键字不适合，请停止检查其他关键字，因为所有剩余关键字至少一样长。 

为什么它有效：

 排序后，算法始终按照从最便宜到最昂贵的顺序考虑关键字。 假设最佳答案包含较长的关键字，而存在较短的未选择关键字。 用较短的关键字替换较长的关键字会保持所选关键字的数量不变，并且不会增加已用空间。 重复这种交换意味着总有一个包含最短可用关键字的最佳解决方案。 该算法正是构造了这个集合，因此它返回的数字是最大的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    words = input().split()

    words = list(set(words))
    words.sort(key=len)

    used = 0
    answer = 0

    for word in words:
        add = len(word)
        if answer > 0:
            add += 1

        if used + add <= n:
            used += add
            answer += 1
        else:
            break

    print(answer)

if __name__ == "__main__":
    solve()
```集合转换会在任何计算开始之前处理重复的关键字。 这是必要的，因为重复项不能一起出现在备忘单上。 

排序依据`len`将单词按照贪婪选择所需的确切顺序排列。 在扫描过程中，`used`存储备忘单的完整当前大小，包括单词之间已放置的所有空格。 

变量`answer`还告诉我们下一个单词之前是否需要分隔符。 第一个选择的单词前面没有空格，而后面选择的每个单词都会添加一个额外的字符。 

当单词无法容纳时，循环立即结束。 所有后面的单词都具有相同或更长的长度，因此它们不可能都适合。 这避免了不必要的检查，也避免了涉及分隔符计数的错误。 

Python 整数在这里不存在溢出问题，因为最大可能的总大小仅为 101000 个字符左右。

import sys
import io

def solve(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n, m = map(int, sys.stdin.readline().split())
    words = sys.stdin.readline().split()

    words = list(set(words))
    words.sort(key=len)

    used = 0
    answer = 0

    for word in words:
        add = len(word) + (1 if answer > 0 else 0)
        if used + add <= n:
            used += add
            answer += 1
        else:
            break

 ## 边缘情况

 在排序之前，重复的关键字会减少为单个选择。 为了：```
10 3
hello hello hi
```该集合仅包含`hello`和`hi`。 该算法将它们排序为`hi`,`hello`, 需要`hi`，然后取`hello`因为包括分隔符在内总共有 8 个字符。 输出为2。 

分隔符可能是单词不适合的原因。 为了：```
7 2
abc defg
```该算法首先接受`abc`，使用 3 个字符。 下一个关键字需要 1 个空格加 4 个字符，因此新的总数将为 8。它被拒绝，生成 1。 

大写和小写关键字保持分离，因为该集合精确地比较字符串。 为了：```
5 2
A a
```排序后的列表包含这两个单词。 第一个使用 1 个字符，第二个添加 1 个分隔符加上 1 个字符，因此答案变为 2。 

第一个关键字有一个特殊的边界条件，因为它不需要前面的空格。 仅当至少已选择一个单词时，该实现才会通过添加分隔符来处理此问题。
