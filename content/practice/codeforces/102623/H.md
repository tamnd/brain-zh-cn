 ## 解决方案
 # 问题理解

 农场是一个网格，每个细胞都有自己的杂草生长速度。 具有价值的细胞`a[i][j]`每时每刻都会获得那么多杂草单位。 在某些时刻结束时，割草机会清除整行或整列，任务是找出所有操作中清除的杂草总量。 

输入给出了增长率网格，然后给出了行和列清除操作的时间顺序。 由于操作时间严格增加，每个事件都可以按顺序处理。 答案是在每个清理时刻清除的所有杂草的总和，取模`998244353`。 

网格尺寸最多为 500 x 500，因此最多有 250000 个单元格。 割草机操作次数可达 300000 次。直接模拟网格需要在每次操作后触摸每个单元格，在最坏的情况下约为 750 亿次操作。 即使为每个操作迭代整个维度也是可接受的，因为维度很小，并且预期的解决方案使用此属性。 

增长率和次数较大的值在计算时需要64位运算。 一个常见的错误是将答案或中间结果存储在 32 位整数中。 另一个微妙的情况是最近行和列都被剪切了。 单元格不记得上次单独剪切其行和上次单独剪切其列的时间。 它的实际杂草量取决于这两个时刻中较新的时刻。 

例如，考虑：```
1 1 2
5
r 1 10
c 1 20
```第一个切口移除`5 * 10 = 50`。 第二次切割没有删除任何内容，因为唯一的单元格已在时间 10 处被清除，并且又增长了 10 时刻，因此总数为`100`。 

仅跟踪最后一个行切割或仅跟踪最后一个列切割的粗心解决方案会错误地将单元格计数为在其中一个操作中从时间 0 开始增长。 

另一个边缘情况是零增长率：```
1 1 1
0
r 1 100
```答案是`0`。 即使贡献为零，实施仍然必须更新削减时间，因为未来的操作取决于这些时间。 

# 方法

 一个简单的方法是保持每个单元格中当前的杂草量。 当时间推进时，将生长添加到每个单元格中，当行或列被修剪时，对该行求和并将其清除。 这完全符合流程，并且很容易证明是正确的。 然而，事件之间的时间间隔可能很长，并且事件数量为 300000。在每个事件之后更新所有单元格会产生成本`O(k*n*m)`，远远超出了极限。 

有用的观察结果是，单元格的增长仅取决于其行或列上次被清除的时间。 对于一个细胞`(i,j)`，如果最后一次行切割发生在`R[i]`最后一次列剪切发生在`C[j]`，那么当前存在的杂草是：`a[i][j] * (current_time - max(R[i], C[j]))`。 

当剪切一行时，我们只需要对该行中的单元格计算这个公式。 这同样适用于柱切割。 由于两个维度最多为 500，因此每个事件检查一个完整维度是可行的。 

蛮力之所以有效，是因为网格很小，但当它重复模拟所有单元时，就会失败。 对独立行和列重置时间的观察使我们能够将每个操作的工作量减少到单行或列扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(k_n_m) | O(n*m) | 太慢了|
 | 最佳| O(k*max(n,m)) | O(k*max(n,m)) | O(n*m) | 已接受 |

 # 算法演练

 1. 存储所有细胞的生长率。 维护两个数组：`last_row[i]`存储最后一刻的行`i`被清除，并且`last_col[j]`存储最后时刻的列`j`被清除了。 最初两者都为零，因为网格开始为空。 
2.当连续`x`被清除的时间`t`，迭代每一列`j`。 单元格中的金额`(x,j)`由行间最晚清空时间决定`x`和列`j`，所以添加：`a[x][j] * (t - max(last_row[x], last_col[j]))`到答案。 处理完该行后，设置`last_row[x] = t`。 
3. 当列`y`被清除的时间`t`，对每一行进行对称操作`i`:`a[i][y] * (t - max(last_row[i], last_col[y]))`然后设置`last_col[y] = t`。 
4. 对答案取模`998244353`添加后以保持值的可管理性。 

为什么有效：对于每个单元格，该算法都会准确添加该单元格被清除时存在的杂草数量。 单元格仅受其自己的行或自己的列上的操作影响。 在两次这样的操作之间，细胞不断生长，并且该生长间隔的起点恰好是前两次清除时间中最近的一次。 每个操作中使用的公式都与这个不变量相匹配，因此每个删除的单元都会被计算一次且仅一次。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m, k = map(int, input().split())

    a = [list(map(int, input().split())) for _ in range(n)]

    last_row = [0] * n
    last_col = [0] * m

    ans = 0

    for _ in range(k):
        typ, x, t = input().split()
        x = int(x) - 1
        t = int(t)

        if typ == 'r':
            lr = last_row[x]
            row = a[x]
            for j in range(m):
                start = lr if lr > last_col[j] else last_col[j]
                ans += row[j] * (t - start)
            last_row[x] = t
        else:
            lc = last_col[x]
            for i in range(n):
                start = last_row[i] if last_row[i] > lc else lc
                ans += a[i][x] * (t - start)
            last_col[x] = t

        ans %= MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```数组`last_row`和`last_col`包含除原始网格之外唯一需要的状态。 它们代表每行的重置时间，因此不需要存储单元格的当前值。 

对于行操作，局部变量`lr`在更新之前保留旧行时间戳。 这很重要，因为贡献必须在割草机清除行之前使用状态。 同样的想法也适用于具有`lc`。 

Python 整数自动处理涉及值高达`10^18`，但模运算使最终答案保持有界。 比较是手动编写的，而不是使用`max`在内循环内部，因为这些循环在最大的情况下可以执行数亿次。

 # 边缘情况

 受行和列剪切同时影响的单元必须使用较晚的重置时间。 在：```
1 1 2
5
r 1 10
c 1 20
```第一个操作添加`5 * 10 = 50`。 在第二次操作之前，时间 10 处的行重置比初始列重置更新，因此第二个贡献是`5 * (20 - 10) = 50`。 该算法分别存储这两个时间戳并取它们的最大值。 

当一行连续被清除多次时，同一行的前一次清除很重要。 例如：```
1 1 2
3
r 1 4
r 1 9
```第一个事件删除`12`，第二个删除`15`。 算法不断更新`last_row`，所以第二次计算从时间 4 开始，而不是从时间 0 开始。 

当时间值非常大时，例如`10^18`，无需特殊处理。 该公式仅对Python整数进行乘法和减法，可以准确地表示这些值。
