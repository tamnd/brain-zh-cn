 ## 解决方案
 ## 问题理解

 我们收到一系列恒星亮度值，但该序列是在线生成的。 每一颗新星出现后，我们都需要当前前缀的美度值。 前缀的美妙之处在于该前缀的每个连续段之间的最小亮度之和，取模`998244353`。 

生成器使任务变得更加困难，因为下一个亮度取决于之前的美丽值。 计算后`A_i`，下一颗星星的计算方法是`A_i`，所以我们无法提前读取整个数组。 

输出是所有计算出的美丽值的异或。 从这一秒到下一秒必须保存的唯一信息是更新生成器所需的当前美感和先前美感值所需的数据结构。 

的价值`n`可以达到`10^7`。 检查所有子数组的解决方案是不可能的，因为大约有`n^2 / 2`子数组，大约是`5 * 10^13`运营。 即使每次更新具有对数因子的算法在这种规模下也是有风险的。 我们需要摊销常数时间更新。 

亮度值几乎可以大到`10^9`，并且美丽值必须以模数处理`998244353`。 生成器还取决于模值，因此错误地混合原始值和模值可能会产生错误的未来之星。 

小前缀也必须正常工作。 对于一颗星星来说，美丽就是那颗星星的亮度。 例如，如果输入是`1 10 0 0 0 7`，唯一的亮度是`7`，所以输出是`7`。 将运行答案初始化为零并忘记处理第一个元素的实现将会失败。 

重复的亮度值是另一​​个常见的错误来源。 例如，序列`[5, 5]`具有子数组最小值`5, 5, 5`，所以美感就是`15`。 仅删除严格较大的值而不是较大或相等的值的单调堆栈将错误地计算相等的值。 

## 方法

 直接的解决方案将存储所有先前的星星，并在每次插入后枚举每个子数组并计算其最小值。 这个方法是正确的，因为它从字面上评估了美的定义。 对于长度前缀`i`，这需要`O(i^2)`工作，并且在所有前缀上，总工作变成`O(n^3)`。 即使通过保持每个起始位置的最小值来改进它仍然需要`O(n^2)`整体运作，远远超出了极限`n = 10^7`。 

有用的观察来自于仅查看附加星形时创建的新子数组。 假设新的亮度是`x`。 所有旧的子数组都保持其先前的最小值。 唯一的新术语是以新位置结尾的后缀。 如果我们知道以当前位置结尾的所有后缀的最小值之和，那么将其添加到全局美度中就会得到新的答案。 

后缀最小值具有结构化行为。 当出现更小的值时，它会替换之前的几个后缀最小值。 这正是单调堆栈处理的情况。 堆栈按升序存储亮度值。 每个条目还存储当前有多少后缀具有该值作为最小值。 当新的较小值到达时，所有较大值都会合并到新值中，因为这些后缀现在具有较小的最小值。 

暴力破解之所以有效，是因为每个子数组最小值都被显式计算，但由于子数组太多而失败。 单调堆栈压缩共享相同最小值的后缀组，从而减少每次插入的摊销`O(1)`时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个前缀 O(n^2) | O(n) | 太慢了|
 | 单调堆栈 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 保持单调递增的堆栈。 每个堆栈元素存储一个亮度值以及最小值为该值的连续后缀的数量。 
2. 维护`cur`，以当前位置结尾的所有后缀的最小值之和。 当新的亮度`x`到达时，它以一个新后缀的最小值开始，因此它将做出贡献`x`。 
3. 当栈顶值大于或等于`x`，删除该条目。 这些后缀组现在有`x`作为他们的最小值，所以从他们的旧贡献中减去`cur`并将他们的计数添加到新组中。 
4. 添加合并组的贡献，其中包含`x`到`cur`，然后将该组压入堆栈。 
5.整个前缀的美感增加了整整`cur`，因为唯一的新子数组是以新星号结尾的后缀。 将这个美丽值添加到 XOR 答案中。 
6. 使用当前的美丽值生成下一个星星，并继续，直到处理完所有星星。 

为什么它起作用：堆栈不变性是每个堆栈条目代表一组以相同最小值结束于当前位置的后缀，并且堆栈中的值严格递增。 当新值到达时，每个受影响的组正是旧最小值大于或等于新值的后缀组。 用新值替换这些组会保留所有后缀最小值，而仅更改其表示形式。 由于每个元素进入堆栈一次并离开一次，因此总的堆栈操作是线性的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, p, x, y, z, b = map(int, input().split())

    stack_val = []
    stack_cnt = []

    cur = 0
    ans = 0

    for i in range(n):
        cnt = 1
        b_mod = b % MOD

        while stack_val and stack_val[-1] >= b:
            v = stack_val.pop()
            c = stack_cnt.pop()
            cur = (cur - (v % MOD) * c) % MOD
            cnt += c

        cur = (cur + b_mod * cnt) % MOD

        stack_val.append(b)
        stack_cnt.append(cnt)

        ans ^= cur

        if i + 1 < n:
            b = (x * cur + y * b + z) % p

    print(ans)

if __name__ == "__main__":
    solve()
```因为输入大小可以达到千万级，所以两个栈数组分开保存，而不是存储元组。 避免元组分配可减少内存开销并提高运行时间。`cur`以模存储`998244353`因为以后每次使用美丽值只需要模块化结果。 堆栈保留原始亮度值，因为比较必须使用星星的真实顺序。 贡献减法使用`v % MOD`，它保留了模运算，同时保持比较正确。 

生成器更新仅在当前美丽被记录后执行。 公式中仍然需要当前亮度，因此在计算下一个值后更新它。 

使用`>=`在堆栈合并的情况下是必要的。 相同的亮度值必须属于同一组，否则相同的后缀将被计算多次。

 ## 边缘情况

 对于一颗星星，堆栈包含一组计数为一的组。 有输入`1 10 0 0 0 7`，算法计算`cur = 7`，将美度设置为`7`，和输出`7`。 没有之前的后缀可以合并，所以直接测试初始化​​。 

对于相等的值，请考虑`2 100 0 0 0 5`。 第一个美女是`5`。 下一个生成的值也是`5`，所以以那里结尾的两个后缀都有最小`5`。 堆栈将旧组和新值合并到`(5,2)`，生产`cur = 10`和最终的美丽`15`为两星序列。 美女的异或是`5 xor 15 = 10`。 这会捕获错误处理平等的实现。 

对于递减序列，每个新值都会替换所有先前的后缀最小值。 堆栈反复折叠成一组。 对于亮度值`[9,8,7]`，美女们是`9`,`25`， 和`46`，所以异或是`9 xor 25 xor 46 = 54`。 该算法处理这个问题是因为每次弹出都会将旧的后缀组转移到新的较小的最小值中。
