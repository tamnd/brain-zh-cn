 ## 解决方案
 ## 问题理解

 将地铁系统视为一个加权图。 每个站点都是一个顶点，同一条线上的连续站点通过边连接，边权重是这些站点之间的行程时间。 线路之间的三个特殊连接是附加边，其权重是传输时间`d`。 

第一行包含三条线路的车站数量，`x`,`y`， 和`z`。 第二行给出了三个交换参数`a`,`b`， 和`c`。 这些确定了三个传输对：`(1, a)`连接到`(2, b + 1)`,`(1, a + 1)`连接到`(3, c)`， 和`(2, b)`连接到`(3, c + 1)`。 

第三行给出每条线路上一趟相邻车站移动的行程时间以及一次换乘所需的时间。 最后一行标识出发线路和车站以及目的地线路和车站。 

输出是最小总行程时间。 路线可以沿着地铁线路向任一方向移动，并且可以在三个换乘对中的任何一个换乘。 由于 Dima 不在换乘站离开地铁，因此这些转乘只是路线中的边缘。 

主要的困难是线条的大小。 每行最多可以包含`10^9`站，因此完整的图表最多可以包含`3 * 10^9`顶点。 即使在一秒的限制内明确地读取这样的图表也是不可能的。 答案不能依赖于迭代所有站点，因此解决方案必须利用几乎每个站点都是完全普通的事实。 

有几种边缘情况可能会使看似合理的解决方案变得错误。 首先是交换端点不在`(a, b)`,`(a, c)`， 和`(b, c)`。 它们在交替线上移动一位。 例如，```
3 3 3
1 1 1
5 1 1 1
1 2 2 1
```起点为1号线2号站，终点为2号线1号站。直达换乘使用1号线1号站和2号线2号站，所以费用为`5 + 1 + 1 = 7`。 将 1 号线车站 1 直接连接到 2 号线车站 1 的解决方案将模拟不存在的换乘，并可能产生较小的错误答案。 

第二个边缘情况是，保持在同一条线上并不一定是最佳的。 例如，```
5 5 5
2 2 2
10 1 1 1
1 1 1 5
```直接乘坐 1 号线费用`4 * 10 = 40`。 更快的路线使用2号线和3号线作为绕行和费用`35`。 仅考虑起点站和终点站在同一条线上时的直接移动的解决方案无法达到最佳效果。 

第三种边缘情况是两个重要站点之间的距离非常大。 考虑```
1000000000 1000000000 1000000000
1 1 1
1 1 1 1
1 1000000000 2 1000000000
```正确答案是`1999999998`。 数字本身很大，但计算只需要一些乘法和加法。 基于显式构建每个站的实现甚至无法表示实际内存或时间内的图。 

## 方法

 最直接的解决方案是构建整个地铁图并运行最短路径算法，例如 Dijkstra。 这是正确的，因为每个可能的运动都由一条边表示，其行进时间恰好作为权重。 

问题是顶点的数量。 在最大限制下有`10^9 + 10^9 + 10^9 = 3 * 10^9`站顶点。 3条地铁线路共包含`3 * 10^9 - 3`普通的线边，三个交汇处再加三个，所以图形正好有`3 * 10^9`最坏情况下的无向边。 邻接表表示已经大致包含`6 * 10^9`邻接条目。 Dijkstra 需要检查数十亿个顶点和边，远远超出一秒的限制。 

关键的观察结果是 Dima 只能在三个固定车站对换线。 在两个如此重要的车站之间，不会发生任何有趣的事情：只有一条地铁线路可用，并且在该线路上的两个位置之间移动的固定成本等于车站距离乘以该线路的行驶时间。 

假设1号线上连续两个重要车站为车站`p`和`q`。 我们可以仅表示这两个端点并将它们与成本的一个加权边连接起来，而不是表示它们之间的每个站`|p - q| * t1`。 

沿线路该部分的任何移动都具有此成本，因此中间站不会为最短路径计算提供任何信息。 

对于每条线路，我们只需要它的两个换乘端点以及起始站或目的地站（如果该站位于线路上）。 因此每条线最多贡献四个顶点。 在所有三行中，压缩图最多有 12 个顶点。 

一旦这些顶点通过加权线段和三个传输边连接起来，原来的问题就是这个小图上的最短路径问题。 Dijkstra 的速度已经足够快了。 

蛮力方法之所以有效，是因为它精确地模拟了每一种可能的运动，但它却失败了，因为几乎所有这些站点都与路线的选择无关。 通过观察，只有换乘站和两个端点才能改变路线的结构，这让我们可以用最多 12 个有意义的顶点来替换数十亿个普通顶点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O((x+y+z) log(x+y+z))`|`O(x+y+z)`| 太慢了|
 | 最佳 |`O(1)`|`O(1)`| 已接受 |

 最佳复杂度在技术上是恒定的，因为压缩图最多包含十二个顶点和恒定数量的边，与`x`,`y`， 和`z`。 

## 算法演练

 1. 在每条线路上创建一组重要站点。 对于 1 号线，换乘站为`a`和`a + 1`。 对于第 2 行，它们是`b`和`b + 1`。 对于第 3 行，它们是`c`和`c + 1`。 还将出发站和目的地站插入各自的线路中。 

我们使用集合是因为​​起点或目的地本身可能与换乘站重合。 这样的站点在压缩图中只能出现一次。 
2. 为每个图分配一个顶点`(line, station)`在这些集合中配对。 

每行最多有四个位置，因此最多有十二个压缩顶点。 实际站数仍然可以大到`10^9`，但它仅存储为普通整数标签。 
3、对每条线路上的重要站号进行排序。 

对于每对连续位置`p`和`q`在一条线上，添加一条带有权重的无向边`abs(p - q) * t`， 在哪里`t`是该线路的行程时间。 

连接连续的重要车站就足够了，因为进入某段线路并最终离开该路段的旅行者没有任何理由去访问不相关的中间站。 整个细分市场的差旅费用是固定的。 
4. 添加三个转移边。 连接1号线车站`a`有2号线站`b + 1`、1号线站`a + 1`含3号线站`c`、2号线站`b`含3号线站`c + 1`。 赋予每条边权重`d`。 

这些正是迪马可以换线的合法位置，因此压缩图保留了每一个可能的换线。 
5. 从起始顶点运行 Dijkstra。 

每条边都有一个正权重，因此 Dijkstra 给出了到达每个压缩顶点的最短行程时间。 目的地是这些顶点之一，因为我们明确地将其插入到重要站点集中。 
6. 返回目标顶点的距离。 

生成的最短路径可能停留在一条线路上、使用一个换乘站或进行多次换乘。 压缩图允许所有这些可能性，包括暂时使用较慢或较快线路并返回原始线路的路线。 

### 为什么它有效

 考虑原始地铁系统中的任何有效路线。 每次路线换线时，都必须访问六个换乘终点站之一。 它还在明确包含的端点处开始和结束。 在任何两个连续的重要车站之间，路线都保持在一条线上，而在它们之间旅行最便宜的方式就是沿该线直接行驶。 压缩图恰好包含该段及其旅行成本。 因此，每条有效的原始路线在压缩图中都具有相同或更低成本的路线。 

相反，压缩图中的每条边都代表地铁线路的真实路段或三个合法换乘之一。 因此，每条压缩路线都可以以完全相同的成本扩展为有效的地铁路线。 因此，这两个图具有相同的最短路径距离，并且 Dijkstra 返回所需的答案。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve(reader=input):
    x, y, z = map(int, reader().split())
    a, b, c = map(int, reader().split())
    t1, t2, t3, d = map(int, reader().split())
    k, i, l, j = map(int, reader().split())

    sizes = [x, y, z]
    times = [t1, t2, t3]

    # Important station positions on each line.
    special = [set(), set(), set()]

    # Interchange endpoints.
    special[0].add(a)
    special[0].add(a + 1)

    special[1].add(b)
    special[1].add(b + 1)

    special[2].add(c)
    special[2].add(c + 1)

    # Start and destination.
    special[k - 1].add(i)
    special[l - 1].add(j)

    # Assign compressed graph ids.
    node_id = {}
    vertices = []

    for line in range(3):
        for pos in sorted(special[line]):
            node_id[(line, pos)] = len(vertices)
            vertices.append((line, pos))

    n = len(vertices)
    graph = [[] for _ in range(n)]

    def add_edge(u, v, w):
        graph[u].append((v, w))
        graph[v].append((u, w))

    # Connect consecutive important stations on each metro line.
    for line in range(3):
        positions = sorted(special[line])
        for p, q in zip(positions, positions[1:]):
            u = node_id[(line, p)]
            v = node_id[(line, q)]
            weight = (q - p) * times[line]
            add_edge(u, v, weight)

    # Add the three legal interchanges.
    transfers = [
        ((0, a), (1, b + 1)),
        ((0, a + 1), (2, c)),
        ((1, b), (2, c + 1)),
    ]

    for left, right in transfers:
        u = node_id[left]
        v = node_id[right]
        add_edge(u, v, d)

    start = node_id[(k - 1, i)]
    target = node_id[(l - 1, j)]

    INF = 10**30
    dist = [INF] * n
    dist[start] = 0

    pq = [(0, start)]

    while pq:
        cur_dist, u = heapq.heappop(pq)

        if cur_dist != dist[u]:
            continue

        if u == target:
            return cur_dist

        for v, weight in graph[u]:
            new_dist = cur_dist + weight
            if new_dist < dist[v]:
                dist[v] = new_dist
                heapq.heappush(pq, (new_dist, v))

    return dist[target]

if __name__ == "__main__":
    print(solve())
```实施的第一部分记录三个线路的长度和速度，然后创建重要站点集。 交换端点是使用显式插入的`a`,`a + 1`,`b`,`b + 1`,`c`， 和`c + 1`。 这是大多数差一错误发生的地方，因此稍后直接写入传输对，而不是间接重建。 

这`node_id`字典映射一个逻辑地铁站，例如`(1, a)`到一个小图索引。 在连接位置之前对位置进行排序，可以将整个普通站点区间变成一个加权边。 如果持仓`p`和`q`是连续的重要站点，有`q - p`相邻的列车运行，因此成本为`(q - p) * times[line]`。 

换乘边是单独添加的，因为它们的成本与站点距离不成正比。 每一件的费用都是准确的`d`，无论两个站的位置如何。 

然后 Dijkstra 仅对压缩图进行操作。 陈旧条目检查`if cur_dist != dist[u]`是标准堆实现细节，可避免在找到更好的路线后处理过时的距离。 早返时`u == target`是安全的，因为 Dijkstra 以非递减距离顺序从堆中删除顶点。 

Python 整数具有任意精度，因此乘法如`(q - p) * times[line]`不能溢出。 这在这里很有用，因为两个因素都可以大到`10^9`。

 ## 边缘情况

 最小尺寸的情况是```
2 2 2
1 1 1
1 1 1 1
1 2 2 1
```1号线站2连接3号线站1，而2号线站1连​​接3号线站2。1号线直达2号线路线费用`1 + 1 + 1 = 3`。 压缩图包含所有四个相关端点，因此不需要对每条线路仅包含两个车站的事实进行特殊处理。 

交换相差一的情况是```
3 3 3
1 1 1
5 1 1 1
1 2 2 1
```第一次传输是在 L1-1 和 L2-2 之间，而不是在 L1-1 和 L2-1 之间。 从L1-2到L2-1，迪马首先从L1-2移动到L1-1，持续时间`5`秒，传输`1`第二，然后从 L2-2 移动到 L2-1`1`第二。 压缩图给出`7`，与真实路线完全匹配。 

同行快捷方式的情况是```
5 5 5
2 2 2
10 1 1 1
1 1 1 5
```1号线直达路线费用`40`。 压缩图还包含序列 L1-1 到 L1-2、L2-3、L2-2、L3-3、L3-2、L1-3，最后是 L1-5。 其成本为`10 + 1 + 1 + 1 + 1 + 1 + 20 = 35`。 Dijkstra 发现了这条路线，因为它将换乘视为普通的图边，而不是根据起始线和目的地线进行假设。 

最大尺寸的情况是```
1000000000 1000000000 1000000000
1 1 1
1 1 1 1
1 1000000000 2 1000000000
```仅将三个立交桥周围的车站和两个端点插入到图中。 距车站的距离很远`1000000000`到车站`1`由一条加权边而不是十亿个顶点表示。 最佳路线从L1站1直接换乘L2站2，然后前往L2站`1000000000`, 给予`999999999 + 1 + 999999998 = 1999999998`。 

所有这些情况背后的中心不变量都是相同的：每个压缩边代表两个连续车站之间最便宜的可能移动，其中路线可以有意义地改变方向或线路。 一旦存在这些边，压缩图中的最短路径正是可能的最短地铁旅程。
