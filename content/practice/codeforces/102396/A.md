 ## 问题理解

 我们有三个箱子，里面有`a`,`b`， 和`c`硬币。 一秒钟内，我们恰好选择了两个不同的箱子，并向每个选定的箱子添加一枚硬币。 我们需要所有三个箱子都以相同数量的硬币结束，并且我们想要最少的秒数。 

输入包含三个初始硬币计数，每个计数介于`1`和`5 * 10^8`。 仅涉及三个值，因此不需要复杂的数据结构。 大的上限是真实信号：每秒执行一次操作的模拟可能需要接近十亿次迭代，这远远超出了 1 秒所允许的限制。 恒定时间或对数解是合适的目标。 

主要的边缘情况是最大的箱子已经具有我们最初可能考虑的目标值。 例如，与```
1
2
3
```粗心的做法可能会尝试将前两个箱子提升到`3`。 赤字是`2`和`1`，而第三个箱子不需要硬币。 由于每次操作都会影响两个箱子，因此前两个箱子不能单独增加不同的数量，而第三个箱子则保持不变。 正确答案是`3`，达到`4, 4, 4`。 

另一个边缘情况是已经相同的配置：```
2
2
2
```答案是`0`。 在检查相等性之前始终执行至少一项操作的模拟将错误地返回正值。 

重复的值也值得关注。 为了```
1
3
3
```答案是`4`， 不是`2`。 升起第一个宝箱`2`还不够，因为每次操作都会提升另外两个箱子中的一个。 正确的最终值为`5`，需要四次操作。 

## 方法

 一种直接的方法是一次模拟一秒钟的操作。 在每一步中，我们都可以选择一对使我们走向平等的箱子，更新它们的值，并在所有三个值匹配时停止。 如果选择适当的话，这是正确的，但秒数本身可能会很大。 

将值排序后`x <= y <= z`，约束下最坏的情况是`x = 1`,`y = z = 5 * 10^8`。 那么最小的答案就是`y + z - 2x = 999,999,998`。 

因此，模拟将执行近十亿次迭代。 尽管每次迭代都是恒定时间，但这对于时间限制来说太长了。 

关键的观察是，一次操作总是总共添加恰好两个硬币。 我们可以推断每个箱子在最终状态下必须收到多少硬币，而不是每秒决定选择哪一对。 

假设最终的共同值为`T`。 三个宝箱需要`T-x`,`T-y`， 和`T-z`额外的硬币。 由于每次操作都会向两个箱子提供一枚硬币，因此所需的增加必须是可配对的。 特别是，所要求的最大增幅不能超过其他两项增幅之和。 

对于最小的胸部，所需的增加是`T-x`，这是三者中最大的。 因此我们需要`T - x <= (T - y) + (T - z)`。 

重新排列给出`T >= y + z - x`。 

所以最小可能的公共值恰好是`T = y + z - x`。 

这个目标总是可以实现的。 其所需增量变为`y + z - 2x`,`z - x`， 和`y - x`。 

第一个恰好是其他两个的总和，因此给予最小箱子的每枚硬币都可以与给予其他箱子之一的硬币配对。 

由于每次操作都会增加两个硬币，因此也可以直接获得操作总数。 所需金币总数为`(y + z - 2x) + (z - x) + (y - x) = 2(y + z - 2x)`。 

除以二即可得到答案`y + z - 2x`。 

因此，整个问题简化为对三个数字进行排序并应用一个公式。

 ## 算法演练

 1. 读取三个胸部值并对它们进行排序，以便`x <= y <= z`。 对三个值进行排序需要恒定的时间，让我们能够推断出最小、中间和最大的箱子，而无需处理它们原始位置的单独情况。 
2. 考虑最终的共同价值`T`。 最小的胸部需要`T - x`额外的硬币，而另外两个则需要`T - y`和`T - z`。 
3. 要求最大赤字不大于其他两个赤字之和。 这是必要的，因为添加到最小箱子中的每一枚硬币都必须同时添加到其他箱子中的一枚硬币。 因此`T - x <= T - y + T - z`。 
4. 重新整理不等式得到`T >= y + z - x`。 选择尽可能小的目标给出`T = y + z - x`，从而最大限度地减少工作量。 
5. 计算最小箱子所需的增加量：`T - x = y + z - 2x`。 

在此目标下，此增加恰好是其他两个增加的总和，因此存在有效的配对操作序列。 
6. 输出`y + z - 2x`。 这已经是操作次数，因为添加的硬币总数是该值的两倍，并且每次操作恰好添加两个硬币。 

该结构背后的不变量是最小箱子所需的增量等于其他两个箱子所需增量的总和。 我们可以将最小箱子所需的每枚硬币与其他箱子所需的一枚硬币配对。 无需任何操作，两次触碰同一个胸部，三缺同时耗尽。 任何较小的目标都会违反配对条件，因此没有解决方案可以使用更少的操作。

```前三行读取三个胸部尺寸。 输入中没有测试用例计数，因此程序只处理一个实例。

Python 整数具有任意精度，因此乘法`2`即使输入值大到是安全的`5 * 10^8`。 在具有固定宽度整数的语言中，相同的表达式仍然可以轻松地在 32 位有符号整数范围内，但使用更宽的整数类型也是无害的。
