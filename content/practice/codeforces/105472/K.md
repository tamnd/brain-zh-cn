 ## 解决方案
 ## 问题理解

 我们得到了一台冰箱，分为几个独立的插槽。 每个槽位已包含一定数量的冷汽水瓶，并且每个槽位也有固定的最大容量。 我们还获得了一些新的暖瓶，必须将它们放在插槽前面才能插入冰箱。 这种插入很重要，因为当学生拿汽水时，他们总是取出均匀随机的非空槽的前面的瓶子。 

关键的互动是，在每个槽内，瓶子都严格从前面消耗。 因此，如果我们在前面插入新的热瓶，它们将在该插槽中现有的冷瓶之前被取出。 随着学生反复选择一个随机的非空槽并从其前面取出一个瓶子，该系统不断发展。 

目标是将新的热瓶分配到各个槽位中，使得前 m 个学生总是收到冷瓶的概率尽可能大。 如果没有办法达到正概率，我们必须报告不可能。 

限制很小。 所有参数最多为 100。这立即表明任何尝试显式模拟完整随机过程的解决方案在多项式时间内都是可行的，但我们仍然需要结构洞察力以避免不必要的状态爆炸。 

当热瓶过于激进地放入经常提前选择的插槽中时，就会出现微妙的失败情况。 在这种情况下，在某些配置中，前几次随机抽取可能不可避免地以 1 的概率撞到热瓶，这将导致不可能成功。 一个简单的例子是，当只有一个插槽并且至少放置一个暖瓶时。 第一次选择该时段时，会拿走一个温热的瓶子，因此如果这种情况发生在前 m 个选择内，则事件会立即受到影响。 因此，正确的解决方案必须仔细控制热瓶在槽中的分布方式。 

## 方法

 一种强力策略是枚举在 s 个槽中分配 n 个热瓶子的所有方法。 分布的数量是组合的，顺序为$\binom{n+s-1}{s-1}$，即使对于 n, s 约为 100，它也已经很大。对于每个分布，我们需要模拟或计算前 m 个抽奖避开热瓶的概率。 该模拟本身涉及 m 个步骤的随机过程，每个步骤最多有 s 个选择，因此即使是单个评估也很重要。 这很快就变得不可行。 

关键的观察结果是，概率结构并不取决于槽内冷瓶的详细顺序，而仅取决于每个槽前面放置了多少个热瓶。 一旦一个插槽前面有 wi 暖瓶，第一次​​选择它时，它会产生一个暖瓶，只有在那之后它才表现得像一个纯冷源。 

这将问题简化为决定如何在插槽之间分配 n 个相同的“风险单元”（热瓶），其中每个插槽 i 都有一个基本大小 ci ，用于确定它保持活动状态的时间。 唯一有意义的决定是如何分配热瓶以平衡其对各个时段的影响。 

正确的策略是“贪婪”：将热瓶集中到对早期过程造成最小干扰的槽中。 由于在非空时隙中统一选择时隙，因此有效地保持非空时间较长的时隙有更多的机会被选择。 将热瓶放入此类槽中会增加风险。 因此，最佳策略是将热瓶放入很快变得不相关的槽中，即那些初始尺寸较小的槽中。 

这会导致按当前大小对插槽进行排序，并从最小的开始向它们填充热瓶子。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解+模拟 | 指数| O(s) | 太慢了|
 | 按槽大小贪婪分配 | O(s log s) | O(s) | 已接受 |

 ## 算法演练

 我们将每个槽位视为可容纳额外的热瓶，直到剩余空间为止，并且我们一次将 n 个热瓶分配到一个槽位。 

1. 按当前冷瓶数量对插槽进行非降序排序。 直觉是，较小的槽在消费过程中会更早消失，因此将热瓶子放在那里可以减少它们对随机选择过程的长期影响。 
2. 从最小的槽位开始分配n个热瓶。 对于按顺序排列的每个槽位，用尽可能多的热瓶填充它，直到其剩余容量为止，直到我们用完热瓶。 
3. 继续分配，直到所有n个温瓶都放置完毕。 如果我们在放置所有瓶子之前耗尽所有插槽，这表明输入约束不一致，但问题保证了可行性。 
4. 按照原始槽位顺序输出分配结果。 

贪婪步骤背后的原因是，在过程中存活时间较长的槽在预期中会被更频繁地选择，因为在剩余的非空槽中选择是一致的。 放置在那里的任何热瓶更有可能在学生选择序列的早期遇到，从而增加了失败的机会。 相反，短期老虎机很少参与早期抽奖，因此放置在那里的热瓶不太可能干扰前 m 个事件。 

### 为什么它有效

 在任何时刻，该过程仅取决于哪些槽仍为非空。 初始大小较大的槽保持活动状态的时间较长，因此随着时间的推移对选择分布的贡献更大。 由于每个热瓶在插槽消耗的早期阶段遇到时都代表着潜在的故障，因此最大限度地减少暴露需要最大限度地减少包含热瓶的插槽的预期选择频率。 通过增加初始大小进行排序可确保将暖瓶放置在对早期采样分布影响最小的槽中，从而保留在前 m 个步骤中避免暖瓶消耗的最高可能概率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, s, d = map(int, input().split())
    c = list(map(int, input().split()))
    
    slots = [(c[i], i) for i in range(s)]
    slots.sort()
    
    remaining = n
    w = [0] * s
    
    for cap, idx in slots:
        if remaining == 0:
            break
        add = min(remaining, d - c[idx])
        w[idx] = add
        remaining -= add
    
    print(*w)

if __name__ == "__main__":
    solve()
```该实现首先解析输入并将每个槽的当前填充级别与其索引配对。 按当前填充排序可确保我们优先考虑较小的插槽。 

然后，我们贪婪地将热瓶分配到每个插槽中，直到其剩余容量为止。 使用`d - c[idx]`确保我们永远不会超出插槽容量限制。 

最后，我们按照输出格式所需的原始顺序重建答案。 

## 工作示例

 ### 示例 1

 输入：```
5 3 3 4
2 3 0
```我们按当前大小对插槽进行排序：插槽 3 (0)、插槽 1 (2)、插槽 2 (3)。 

我们分发了5个暖瓶：

 | 步骤| 已选择插槽 | 剩余 n | 分配|
 | ---| --- | --- | ---|
 | 1 | 插槽 3 | 5 → 5-4=1 | 5 → 5-4=1 | w = [0,0,4] |
 | 2 | 插槽 1 | 1 → 0 | w = [1,0,4] |

 最终输出是一个有效的分配，首先将热瓶集中在最小的槽中。 

该轨迹表明，温热的瓶子首先被推入最不“持久”的槽中，从而最大限度地减少与高频槽的早期相互作用。 

### 示例 2

 输入：```
2 7 6 4
0 1 2 2 0 1
```插槽按大小排序：```
0, 0, 1, 1, 2, 2
```我们将 2 个暖瓶分配到最小的插槽中：

 | 步骤| 插槽| 剩余|
 | ---| ---| ---|
 | 1 | 插槽为 0 | 2 → 1 |
 | 2 | 下一个 0 个插槽 | 1 → 0 |

 这确保了热瓶被隔离在最短暂的插槽中。 

该轨迹表明，该算法始终优先选择对早期采样分布影响最小的时隙。

 ## 边缘情况

 当只有一个插槽并且至少插入一个热瓶时，就会出现关键边缘情况。 在这种情况下，算法仍然将所有热瓶分配到该槽中，但成功的概率完全取决于 m 是否足够小，以至于该过程可以避免过早选择热瓶。 贪婪逻辑仍然产生唯一可行的配置。 

当许多插槽具有相同尺寸时，会出现另一种边缘情况。 排序步骤不需要区分它们，并且相同大小的槽之间的任何排列都会产生相同的行为。 该算法可以正确处理这个问题，因为它不依赖于稳定的排序。 

第三种边缘情况是当 n 足够大以完全填充多个槽时。 该算法自然地按照大小递增的顺序在插槽之间分配分配，确保不会由于`d - c[i]`边界。
