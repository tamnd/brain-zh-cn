 ## 解决方案
 ## 问题理解

 我们得到了一系列涵盖假期长度的每日温度$n$。 我们必须选择一个恰好连续三天的连续块：第一天徒步到湖边，第二天休息（出于炎热的考虑而忽略），第三天徒步返回。 只有这两个徒步日很重要，旅行的不适感被定义为这两个徒步日中的最高温度。 

所以对于每个有效的开始日$d$，我们看一下这对温度$(t_d, t_{d+2})$，我们想要最小化$\max(t_d, t_{d+2})$。 输出是最佳起始日以及该最大值对应的最小值。 如果多个起始日达到相同的最小值，我们选择最小的起始日索引。 

约束条件$3 \le n \le 50$立即告诉我们，即使是二次或三次解也可以在限制内轻松运行。 直接扫描所有可能的开始日期就已经足够了。 不需要高级的数据结构或优化。 

一个微妙的边缘情况来自平局决胜。 如果两个起始位置产生相同的最高徒步温度，我们必须选择最早的一个。 例如，如果温度是$[10, 1, 10, 1]$，然后从第一天开始给出 max$10$，从第 2 天开始给出 max$10$同样，但我们必须输出第一天。 

另一种边缘情况是最佳解决方案出现在数组的最末端。 由于我们访问$d+2$，最后一个有效起始日是$n-2$。 一个常见的错误是迭代到$n-1$，这会索引越界或忽略有效的候选者。 

## 方法

 暴力方法尝试每一个可能的开始日$d$从 1 到$n-2$。 对于每个$d$，它计算两个远足日温度的最大值$t_d$和$t_{d+2}$，并跟踪迄今为止看到的最小值。 这是正确的，因为每个有效行程都被仅考虑一次。 

这种方法的成本是$O(n)$，因为每个候选者都是在恒定时间内评估的，并且有$n-2$候选人。 即使我们扩展问题以检查更复杂的模式，这种滑动窗口枚举仍然很便宜。 

除此之外没有任何有意义的优化，因为每个开始日都是独立的。 问题的结构已经很小了：一个固定大小的窗口，在两个端点上进行简单的聚合。 关键的观察是中间的一天是无关紧要的，所以我们在计算中永远不需要考虑它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | ---| --- | --- |
 | 蛮力 |$O(n)$|$O(1)$| 已接受 |
 | 最佳 |$O(n)$|$O(1)$| 已接受 |

 事实上，“最佳”解决方案就是通过干净的簿记进行强力扫描。 

## 算法演练

 我们处理所有有效的起始位置并计算每个候选行程的成本。 

1. 初始化变量来存储最佳答案：最低温度的大值和最佳开始日期的占位符。 我们使用非常大的初始值，以便任何实际温度都会改善它。 
2. 迭代所有开始日期$d$从 0 到$n-3$在从零开始的索引中。 这确保了两者$d$和$d+2$是有效的指数。 
3. 对于每个$d$，计算值$v = \max(t[d], t[d+2])$。 这代表了该次旅行徒步旅行当天最糟糕的温度。 
4. 如果$v$严格小于迄今为止看到的最佳值，将最佳值和最佳起始日更新为$d$。 我们还通过仅更新严格改进来隐式处理平局打破，这保留了最早的索引。 
5. 完成扫描后，输出转换回基于 1 的索引的最佳起始日以及最佳值。 

### 为什么它有效

 每个有效行程恰好对应一个索引$d$，并且该旅行的成本仅取决于两个固定元素$t[d]$和$t[d+2]$。 由于我们对所有这些对进行一次评估，并且始终保留所有候选值中的最小值，因此存储的答案是全局最优的。 一旦记录了第一个出现的值，决胜局的正确性就不会覆盖相等的值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
t = list(map(int, input().split()))

best_val = float('inf')
best_d = 0

for d in range(n - 2):
    val = max(t[d], t[d + 2])
    if val < best_val:
        best_val = val
        best_d = d

print(best_d + 1, best_val)
```核心循环直接实现了所有有效起始天数的枚举。 使用从零开始的索引简化了边界处理，因为我们自然会停在$n-3$。 条件`val < best_val`强制执行最小化和正确的打破平局，因为早期的指数永远不会被相等的指数取代。

 ## 边缘情况

 对于最小情况$n = 3$，正好有一个可能的行程。 该算法仅评估$d = 0$, 计算$\max(t[0], t[2])$。 没有歧义，并且循环只执行一次。 

对于常量数组，例如$[5,5,5,5,5]$，每个候选人产生相同的值。 因为我们只更新严格的改进，所以第一个索引仍然被选择，确保正确的平局打破，而不需要对索引进行任何明确的比较。 

对于边界重的情况（例如严格递增序列），最优解始终位于$d = 0$，因为后面的位置与更大的值配对$d+2$。 扫描自然会保留这一点，无需特殊处理。 

对于严格递减序列，最佳选择向两个端点最小的末端移动。 由于循环包括$d = n-3$，始终会考虑最终候选者，从而防止出现相差一的错误。
