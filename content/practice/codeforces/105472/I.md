 ## 解决方案
 ## 问题理解

 我们得到了循环赛的完整结果$n$参赛者，但结果是增量编码的。 对于每对参赛者$i < j$，我们知道参赛者是否$j$失败的参赛者$i$。 这定义了一个完整的有向锦标赛图，其中每一对都恰好有一个有向边。 

现在，我们想象一种顺序，参赛者被一一“引入”。 最初每个人都在左侧。 当参赛者入选时，他们会永久移至右侧。 在任何时刻，一些参赛者已经入选（右侧），而其余的则尚未入选（左侧）。 

我们在此过程中跟踪的数量是“坏边”的数量，即已经位于右侧的参赛者输给仍在左侧的参赛者的比赛。 每次我们引入某人时，该值都会发生变化，因为从右到左交叉的边会被重新分类。 

任务是选择一个归纳顺序，使整个过程中此类坏边的最大数量最小化，并输出这个最小可能的最大值。 

约束条件允许$n \le 5000$，输入描述了一个密集的结构：完整的锦标赛。 这立即表明$O(n^2)$预处理是可以接受的，但是任何立方或更糟的东西都太慢了。 任何每一步重复重新计算全局属性的解决方案都将变成$O(n^3)$并失败。 

当排序“对抗性敏感”时，就会出现微妙的边缘情况：即使最终的排序看起来不错，糟糕的归纳序列也会暂时产生大量坏边缘。 例如，如果参赛者 1 击败了所有人，但最后入选，那么所有早期的入选可能会产生许多坏边，其中涉及边进入 1，具体取决于方向。 这表明问题不在于最小化最终结构，而是随着时间的推移控制动态剪切。 

## 方法

 一个蛮力的想法是尝试归纳顺序的所有排列。 对于每个订单，我们模拟该过程并计算遇到的坏边缘的最大数量。 模拟本身可以通过跟踪每个新引入的节点相对于已引入的节点创建或删除的边数来维护。 这已经花费了$O(n)$每一步，所以一次模拟是$O(n^2)$，并且枚举所有排列是$O(n! \cdot n^2)$，这是完全不可行的。 

关键的观察结果是，该过程仅取决于顶点的相对顺序以及顶点之间的边的方向。 当引入一个顶点时，该顶点和其余顶点之间的所有边都会以可预测的方式成为切割的“主动贡献者”。 这建议将问题重新定义为在排列的前缀上维持动态值。 

我们可以逆向思考，而不是向前思考。 假设我们构建从最后引入到第一个引入的最终顺序。 然后在任何步骤中，我们都会向部分构建的后缀添加一个顶点。 给定时间的坏边与此反向构造中从已添加的顶点到尚未添加的顶点的边完全对应。 

这将问题转化为对于每个顶点，根据方向维护有多少条边指向所选前缀或后缀。 然后，最佳排序由贪婪结构控制：在每一步中，我们都希望添加导致当前坏边计数尽可能最小增加的顶点，但我们还需要考虑未来的选择如何取决于此结构。 

关键的见解是，目标相当于最小化锦标赛中排列的所有前缀的最大切割大小。 这是一个经典的“最小化最大前缀切割”问题，可以通过二分查找答案来解决$k$，然后检查可行性。 

对于固定的$k$，我们询问是否存在这样的排序：在每个前缀处，从当前前缀到其补集的边数最多为$k$。 这成为一个约束满足问题，其中每个顶点根据其位置对切割有贡献。 我们可以通过始终选择一个位置不违反边界的顶点来贪婪地构建排序，从而保持增量计数。 

可行性检查可以使用类似度数的簿记来实现：当一个顶点添加到前缀时，我们更新它对剩余集合有多少条传出边。 如果在任何时候所有剩余​​的选择都会超过$k$，配置无效。 

这将问题简化为单调谓词$k$，启用二分搜索$O(\log n)$与一个$O(n^2)$查看。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力排列 |$O(n! \cdot n^2)$|$O(n^2)$| 太慢了 |
 | 二分查找+可行性检查 |$O(n^2 \log n)$|$O(n^2)$| 已接受 |

 ## 算法演练

 我们首先预先计算锦标赛矩阵，以便我们可以查询是否$i$节拍$j$在$O(1)$。 这使我们能够快速评估任何对之间的贡献。 

1.我们定义一个函数`check(k)`决定是否存在最大坏边永远不会超过的归纳阶$k$。 该功能是该解决方案的核心。 
2. 内部`check(k)`，我们维护一组未放置的顶点并模拟构建从左到右的顺序。 对于每个顶点，我们跟踪已放置的顶点有多少条边指向它，因为这些决定了移动时当前的坏边计数。 
3. 在每一步中，我们尝试选择一个顶点，使坏边的运行总数保持在限制范围内$k$。 放置顶点的​​贡献取决于它丢失了多少已放置的顶点，因为这些边会成为从右到左的违规。 
4. 我们贪婪地选择任何其加法使累积计数可行的顶点。 如果在某个步骤中没有顶点可以添加而不超过$k$，我们得出结论，这$k$太小了。 
5.我们二分查找最小的$k$为此`check(k)`返回真。 

正确性取决于以下事实：可行性是单调的$k$。 如果某些订单存在有效的订单$k$，那么对于任何更大的$k$，因为放宽约束不能使有效序列无效。 

贪婪可行性检查之所以有效，是因为在每一步中，只有顶点的增量贡献很重要，并且该贡献仅取决于固定的锦标赛边缘和当前的前缀集。 该结构确保，如果在某个阶段无法放置某个顶点，则没有具有相同前缀大小的替代排序可以在不增加最大值的情况下修复该约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
beats = [[0] * n for _ in range(n)]

for i in range(1, n):
    s = input().strip()
    for j, ch in enumerate(s):
        if ch == '1':
            beats[i][j] = 1
        else:
            beats[j][i] = 1

def check(k):
    placed = [False] * n
    indeg = [0] * n
    order = []

    for _ in range(n):
        found = -1

        for v in range(n):
            if placed[v]:
                continue

            # simulate adding v
            inc = 0
            for u in order:
                if beats[v][u] == 1:
                    inc += 1

            if indeg[v] + inc <= k:
                found = v
                break

        if found == -1:
            return False

        v = found
        placed[v] = True
        order.append(v)

        for u in range(n):
            if not placed[u] and beats[u][v] == 1:
                indeg[u] += 1

    return True

lo, hi = 0, n * (n - 1) // 2
ans = hi

while lo <= hi:
    mid = (lo + hi) // 2
    if check(mid):
        ans = mid
        hi = mid - 1
    else:
        lo = mid + 1

print(ans)
```该代码显式构建锦标赛表示，将定向结果存储在矩阵中。 这`check`函数模拟构建排序，同时为每个未放置的顶点维护有多少已放置的顶点击败它。 该值对应于如果此时添加顶点将创建多少条坏边。 

在每个步骤中，我们都会扫描所有未放置的顶点并计算它们的增量成本。 这次扫描是$O(n)$，并且计算每个增量也是$O(n)$在最坏的情况下，给予$O(n^2)$根据可行性检查。 二分搜索将其包装在对数因子中。 

一个微妙的点是`indeg[v]`不是图中真正的入度，而是“从放置的顶点到 v 的边”的动态计数。 这正是决定放置 v 是否违反阈值的因素，因为这些边对应于从右到左的坏对。 

## 工作示例

 考虑一个由三名玩家组成的小型锦标赛，其中玩家 2 击败 1，玩家 3 击败 2，玩家 1 击败 3。 

### 小型项目的可行性检查$k$| 步骤| 放置集| 指数状态| 选定的顶点| 推理|
 | ---| --- | ---| ---| --- |
 | 1 | {} | 全部 0 | 1 | 最初全部有效 |
 | 2 | {1} | 基于 1 的更新 | 2 | 2 不超过 k |
 | 3 | {1,2} | 又更新了 | 3 | 最终排名|

 该轨迹表明，当结构是循环时，由于贡献是分布式的，因此仍然存在多个有效订单，且最大违规较小。 

现在考虑一个传递性锦标赛，其中每个编号较高的玩家都击败所有编号较低的玩家。 

| 步骤| 放置集 | 指数状态| 选定的顶点 | 推理|
 | ---| --- | ---| --- | --- |
 | 1 | {} | 全部 0 | n | 任何同等选择 |
 | 2 | {n} | 为他人增加| n-1 | n-1 每一步都会降低未来的灵活性|
 | 3 | ... | 增长指数| ... | 最坏情况累积|

 这表明早期的选择可以放大后来的约束，这就是为什么必须在全局范围内检查贪婪的可行性。

 ## 边缘情况

 一个关键的边缘情况是锦标赛是完全可传递的，这意味着每个索引较高的参赛者都会击败所有索引较低的参赛者。 在这种情况下，如果顺序逆转得不好，任何强大玩家的早期引入都会在未来产生许多不利的优势。 该算法通过累积来处理这个问题`indeg`单调增长的值，迫使可行性检查拒绝小值$k$。 

另一个边缘情况是几乎循环的锦标赛，其中每个顶点都击败其他顶点的一半。 在这里，增量贡献是平衡的，并且每个步骤中多个顶点仍然可行。 里面的贪心选择`check(k)`仍然会成功，因为没有顶点过早地被唯一强制。 

退化的情况是$n=1$，其中没有边，也没有坏对。 可行性函数立即接受$k=0$，因为循环在没有施加任何约束的情况下终止。
