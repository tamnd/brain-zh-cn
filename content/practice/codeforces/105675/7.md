 ## 解决方案
 ## 问题理解

 竞赛中的每个任务都由几个独立的“分数组”组成，每个组都可以全部完成或跳过。 如果你参加一个小组，你会得到该小组的满分； 如果你跳过它，你就不会从该组中得到任何东西。 

每个任务都有一个约束：您不允许跳过任务内的所有组。 因此，对于每个任务，您必须选择其组的非空子集。 总分是所有任务中所有选定组的总分，问题是是否有可能使这个总分恰好等于目标值。 

输入给出了多个任务。 对于每个任务，您都会获得一个表示其组分数的正整数列表。 输出是一个简单的可行性答案：是否存在总和等于所需值的有效组选择（遵守“每个任务非空”规则）。 

全局结构很重要：任务内的选择是局部的，但最终的约束在所有任务中都是全局的。 这使得它成为一个受约束的子集和问题，每个块都强制包含在内。 

任务数量和值总数的界限很大，达到约 10^5 规模。 这立即排除了任何尝试每个任务组的所有子集或在不压缩的情况下对原始元素运行背包的解决方案。 每个任务接近 O(总元素 × 目标) 或指数的解决方案将不会通过。 

一种微妙的边缘情况来自于只有一组的任务。 在这种情况下，选择是强制的，因为子集必须非空，并且唯一可用的子集是单例。 另一个重要的边缘情况是，当所有组值相对于目标都很大时，即使每项任务都必须做出一些贡献，也无法达到较小的总和。 

## 方法

 如果我们忽略结构，最直接的解释是枚举每个任务内的所有有效选择，计算每个任务的每个可能的总和，然后在所有任务中组合这些任务总和。 对于具有 k 组的单个任务，这已经产生 2^k - 1 个可能的值。 将这些跨 n 个任务组合起来会导致指数爆炸，其中组合的数量会在多个任务之间成倍增加。 即使 k 很小，状态总数也会变得天文数字般大，甚至在最坏的情况下生成所有每个任务的总和也已经花费了 O(k·2^k)。 

关键的观察是，除了可实现的总和之外，我们实际上并不关心每个任务的内部结构。 每个任务都会贡献一个小的“可行总和集”，全局问题变成从每个集中精确选择一个值并将它们相加以达到目标。 但是，直接存储全套还是太大了。 

关键的简化来自于注意到在每项任务中，我们被迫至少选择一组。 这意味着每个任务都会贡献一个基本值加上可选的额外贡献。 如果我们在一项任务中选择最少的组，那么其他一切都将成为相对于该基线的“额外选择”。 以这种方式重新表述每个任务将问题转化为有界子集和，其中每个任务都有固定的基本贡献和一组可选增量。 

现在问题变成了任务上的标准背包：对于每项任务，我们必须选择一个强制性项目（基线），并可选择添加剩余值的任何子集。 由于目标和很小（大约 10^5），因此对可能的和进行位集动态编程变得可行。 我们首先累积强制性基线总和，然后尝试看看是否可以使用所有可选贡献来达到剩余的差异。

这将结构从每个任务的指数结构简化为总和上的单个全局 DP，其中每个值都被处理一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力（每个任务子集 + 全局组合）| O(∏ 2^{k_i}) | O(∏ 2^{k_i}) | O(∏ 2^{k_i}) | O(∏ 2^{k_i}) | 太慢了 |
 | 带有位集的 DP 超过扁平化选择 | O(total_sum × n) 或 O(总元素 × S / 字大小) | O(S)| 已接受 |

 ## 算法演练

 1. 对于每个任务，计算最小的组值并将其添加到运行基数总和中。 这代表我们被迫从每项任务中获得的最低分数，因为我们不能将任务留空。 

2. 对于每项任务，将除选定的强制性基线之外的每个组值视为可选的额外贡献。 基线的自然选择是最小的元素，因为它最大限度地减少了强制成本，并为实现目标留下了更大的灵活性。 

3. 处理完所有任务后，通过从所需总和中减去基本总和来计算我们仍需要达到目标的剩余金额。 如果该值为负数，则答案立即不可能，因为即使采用每个任务的最小值也已经超出了目标。 

4. 构建一个布尔 DP（位集），其中 dp[x] 指示我们是否可以在所有任务中使用可选贡献来实现额外的总和 x。 

5. 初始化 dp[0] = true。 这相当于不选择任何可选附加功能。 

6. 迭代所有任务中的所有可选值，并且对于每个值 v，更新 dp，以便任何先前可达的总和 x 也使 x + v 可达。 此步骤是全局应用的经典子集和转换。 

7. 处理完所有可选值后，检查 dp[remaining] 是否为 true。 如果是，则目标总和在约束下是可以实现的，否则就不能实现。 

### 为什么它有效

 每个任务被分解为固定的强制性贡献加上独立的可选增量。 强制性部分确保始终满足“每个任务的非空子集”约束。 可选部分形成独立项目的标准子集选择问题。 由于在此分解之后所有任务都是独立的，因此将所有可选值合并到一个全局子集和 DP 中可以保留所有有效组合。 DP 状态准确地捕获了可实现的额外总和的集合，因此达到目标相当于找到可选贡献的有效子集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, s = map(int, input().split())

    base = 0
    optional = []

    for _ in range(n):
        k = int(input())
        arr = list(map(int, input().split()))

        m = min(arr)
        base += m

        for v in arr:
            if v != m:
                optional.append(v)

    if base > s:
        print("NO")
        return

    target = s - base

    dp = 1  # bitset: dp[x] = bit x reachable

    for v in optional:
        dp |= (dp << v)
        if dp >> target & 1:
            break

    if (dp >> target) & 1:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```该代码首先将每个任务转换为强制性的最低贡献和可选增量列表。 位集`dp`是用作压缩布尔数组的整数，其中移位`v`添加所有可以扩展的总和`v`。 这避免了完整的 O(n·s) 数组并使用位操作保持快速转换。 

检测到目标位后提前退出是一个重要的优化：一旦所需的总和达到，就不需要进一步处理。

 ## 边缘情况

 当跨任务的最小要求值总和已经超过目标时，算法立即拒绝，而不构建任何 DP。 例如，像这样的情况`n=3`，每个任务都有最小值`5`，和目标`10`在考虑可选选择之前失败，因为基线已经是`15`。 

当每个任务只有一个子任务时，算法退化为固定总和检查。 没有可选值，因此 DP 仍然存在`{0}`，答案仅取决于强制总和是否等于目标。 

当存在许多小的可选值时，位集移位操作会累积密集的可达状态。 DP 正确地合并了它们，因为每个移位完全对应于一次选择该值，并且重复移位自然会考虑组合而不会重复计算。
