 ## 解决方案
 ## 问题理解

 该问题给出了由道路连接的城市的无向、未加权图。 Lex从城市1开始，必须到达城市N。一些城市被标记为“债务城市”，这意味着不希望经过它们。 

路径的评估分两个阶段。 首先，我们统计一下路径上出现了多少个债务城市。 其次，在所有实现债务城市数量尽可能少的路径中，我们选择道路台阶数最少的一条。 

所以目标不仅仅是通常意义上的最短路径。 相反，每个城市如果属于债务集，则惩罚为 1，否则为 0。 我们想要一条从 1 到 N 的路径，以最小化沿路径的这些惩罚的总和，并且在所有此类路径中，我们最小化所使用的边的数量。 

这些约束将我们推向每条边接近线性或对数的图遍历。 对于多达 100000 个城市和 100000 条道路，任何尝试枚举路径或对路线进行指数搜索的解决方案都将立即失败。 即使是节点上的二次方法也已经太大了，因为在 1 秒的限制下不可能进行 10^10 次操作。 

一个关键的微妙之处是优化是按字典顺序进行的。 如果我们只最小化距离，我们可以使用 BFS。 如果我们只最小化债务数量，我们还可以使用带有节点权重的最短路径。 难点在于两者都必须按顺序优化，而且都不能忽视。 

一些边缘情况很容易处理不当。 

如果城市1或城市N是债务城市，则成本必须包括它们。 例如，如果 1 是债务城市而 N 不是，并且存在 1 到 N 的直接边，则正确答案是债务计数 1 和距离 1，而不是 0 和 1。 

另一个问题是，当步数较多的路径避开债务城市，而较短的路径则穿过债务城市时。 例如，三角形 1-2-N（其中 2 为债务）和替代的较长路线 1-3-4-N（没有债务城市）应该更喜欢较长的路线，因为债务最小化占主导地位。 

最后，对于相同的债务数量，可能存在多个最佳路线。 在这种情况下，我们仍然必须选择边数最少的那个，而不是任意打破平局。 

## 方法

 一个蛮力的想法是枚举从 1 到 N 的所有简单路径，计算每条路径包含多少个债务城市及其长度，然后选择最佳路径。 这是正确的，因为它准确地评估了目标，但图中简单路径的数量可能呈指数增长。 在密集甚至中等连接的图中，路径的数量变得远远超出任何可行的限制，在最坏的情况下很容易超过 2^N。 这使得即使对于小图也无法使用暴力破解。 

关键的观察结果是，这是一个最短路径问题，其中每个节点都会贡献成本。 沿边的每个转换都具有相同的结构：移动到邻居会使路径长度增加 1，进入节点可能会使债务计数器增加 1。这意味着每个状态都可以用一对值表示，我们可以按字典顺序比较路径。 

当我们将距离视为元组时，这种结构正是 Dijkstra 算法所支持的。 每个节点都分配有一个最知名的对（debt_count、steps）。 当探索邻居时，我们更新这些对并始终保留字典顺序最小的一对。 这是有效的，因为两个组件都是非负的，并且路径扩展只会添加到它们，从而保留最佳子结构。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（所有路径）| 指数| O(N) 递归堆栈 | 太慢了|
 | Dijkstra 与 (债务, dist) | O(M log N) | O(M log N) | O(N + M) | 已接受 |

 ## 算法演练

 我们将每个城市建模为一个节点，如果它是债务城市，则成本等于 1，否则为 0。我们希望使用字典松弛将最佳成本从城市 1 传播到所有其他城市。

1. 初始化一个距离数组，其中每个条目存储一对 (debt_count, distance)。 将所有值设置为字典意义上的无穷大，这意味着非常大的对。 对于起始节点1，将其成本设置为(isDebt[1], 0)。 这反映出我们在走任何道路之前就已经站在城市 1 了。 
2. 使用按 (debt_count, distance) 排序的优先级队列。 压入起始状态 (isDebt[1], 0, 1)。 这确保我们始终首先扩展当前最著名的状态。 
3. 当队列不为空时，提取字典对最小的节点。 如果该状态已经比该节点存储的最佳值更差，则跳过它，因为已经找到了更好的路由。 
4. 对于当前节点的每个邻居，计算候选状态。 新的债务计数是当前债务加上isDebt[neighbor]，新的距离是当前距离加1。这反映出我们又走了一条路，可能会进入一个债务城市。 
5. 如果该候选对按字典顺序小于邻居的存储值，则更新它并将其推入队列。 
6. 处理完所有可达状态后，城市 N 的答案就是存储的对 (debt_count, distance)。 

为什么它有效是基于这样一个不变式：每当我们从优先级队列中最终确定一个节点时，我们就已经找到了它的最佳字典对。 任何替代路径要么已经被处理，要么在某个较早的步骤中具有更差的前缀，并且由于所有扩展仅添加非负值，因此它永远不会在以后变得更好。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m, d = map(int, input().split())
    debt_set = set(map(int, input().split()))

    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    INF = (10**18, 10**18)
    dist = [INF] * (n + 1)

    start_cost = (1 if 1 in debt_set else 0, 0)
    dist[1] = start_cost

    pq = [(start_cost[0], start_cost[1], 1)]

    while pq:
        dcnt, dlen, u = heapq.heappop(pq)

        if (dcnt, dlen) != dist[u]:
            continue

        for v in g[u]:
            ndcnt = dcnt + (1 if v in debt_set else 0)
            ndlen = dlen + 1
            nd = (ndcnt, ndlen)

            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (ndcnt, ndlen, v))

    print(dist[n][0], dist[n][1])

if __name__ == "__main__":
    solve()
```该图被存储为邻接列表以支持快速邻居迭代。 优先级队列存储的状态首先按债务计数排序，然后按路径长度排序，确保字典顺序的正确性。 

一个常见的陷阱是忘记债务成本与节点而不是边相关。 这就是为什么更新添加了`v in debt_set`当进入邻居时，而不是离开当前节点时。 

另一个微妙的点是初始化。 起始节点立即贡献其债务成本，因为路径已经包含它。

 ## 边缘情况

 一个重要的边缘情况是起始城市本身就是债务城市。 该算法正确地将起始成本初始化为立即包含该城市。 对于像这样的输入`1 -> 2`其中城市 1 在债务列表中，初始状态已经是`(1, 0)`，最终的答案反映了不可避免的成本。 

另一种情况是，目的地是债务城市，但只能通过非债务路径到达。 该算法仍然正确地计算目的地，因为成本是在进入节点 N 时添加的，而不是在路径完成时添加的。 

第三种情况是多条路径具有相同的债务成本但长度不同。 优先级队列确保在相等的债务值中，首先扩展较短的路径，并且字典比较保留正确的顺序。
