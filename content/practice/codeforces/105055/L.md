 ## 问题理解

 我们获得了多组洒水包，其中每个包包含固定的正数洒水，并且必须全部使用或根本不使用。 目标是决定我们是否可以将所有可用的包分成恰好两组，以便两组具有相同的洒水总数，并且两组都不是空的。 

这不仅仅是抽象意义上的划分问题。 每个元素必须恰好分配给两个箱中的一个，我们要问的是两个箱中的总和是否可以使两边相等且严格为正。 换句话说，我们正在寻找将数组划分为两个总和相等的非空子集。 

输入大小最多可达 200,000 个元素，每个元素的值最多为 200,000 个。 这立即排除了分区上的任何子集枚举或指数搜索。 即使是对和的伪多项式动态规划也太大了，因为在最坏的情况下总和可以达到大约 4 × 10^10，这远远超出了任何可行的 DP 表。 

该结构还排除了基于排序或本地决策的贪婪方法。 像“继续选择最小值直到总和的一半”这样的天真的尝试会失败，因为可行性取决于组合结构，而不是顺序。 

一个微妙的边缘情况是总和为奇数。 在这种情况下，无论排列如何，都不可能分成两个相等的整数和。 例如，如果输入是`1 2 3`，总和为 6 并且可能存在分割，但如果输入是`1 2 2`，总和为 5，并且不存在解决方案，即使部分分组可能看起来很有希望。 

另一种极端情况是所有元素都相同。 如果我们有`k`相同的包，那么唯一可能的分区总和是该值的倍数。 我们是否可以分裂完全取决于我们是否可以在每边总共选择偶数个元素，这再次减少了可分性约束而不是排列。 

## 方法

 暴力方法尝试将每个包分配给 Débora 或 Lívia，并检查任何分配是否产生相等的非零总和。 这相当于迭代所有子集并检查任何子集总和是否等于总和的一半。 由于有 2^N 次分配，对于 N 达到 200,000 的情况，这立即变得不可行。 

经典的优化是对可实现的总和进行背包式动态规划。 然而，即使这样也会失败，因为所有值的总和可能非常大。 DP 状态空间取决于总和，而不仅仅是 N，并且这里的总和在实践中是无界的。 

关键的观察是我们没有被要求找到特定的分区，甚至优化任何东西。 我们只需要确定存在即可。 这将问题转变为关于多重集是否可以形成两个等和组的结构问题。 

如果存在这样的分区，则总和必须是偶数，并且必须存在一个子集，其总和恰好是它的一半。 然而，由于所有元素都是正整数并且约束条件很大，因此需要进行更深层次的简化：我们实际上不需要构造子集，只需验证约束条件下的可行性。 

关键的见解是，问题退化为检查总和是否均匀，而不是在退化的单元素情况下。 如果至少有一个包裹，并且允许我们拆分所有物品，那么唯一的障碍就是当 N = 1 时奇偶性和微不足道的不可能性。 

这是因为对于任何至少有两个元素的偶数总和，原则上我们总是可以贪婪地重新排列分配以达到总和的一半，除非我们处于病态的单元素配置中。 由于每个元素只能使用一次，并且分组大小没有限制，因此当总和为偶数且 N > 1 时，始终保证可行性。 

因此，问题简化为恒定时间检查。

 ## 算法演练

 我们将问题简化为对数组进行一些确定性检查。 

1. 计算所有喷洒包的总和。 

总和代表必须在两种饮料之间平均分配的总金额。 
2. 检查总和是否为偶数。 

如果它是奇数，则不可能分成两个相等的整数和，因此我们立即得出失败的结论。 
3. 检查包裹数量是否至少为2个。 

如果只有一个包裹，就无法分给两个人，而且一侧也必然是空的。 
4. 如果两个条件都成立，则断定存在有效分区。 

推理是，只要有至少两个正整数甚至总和，两组之间的重新分配总是可以通过适当分配元素来平衡总和来实现。 

### 为什么它有效

 不变的是我们总是试图将总和的一半表示为所选元素的总和。 由于所有因素都是积极的，我们可以将这个过程视为逐步建立目标总和。 当总和为偶数并且至少有两个元素时，总是可以灵活地为每一侧分配至少一个元素，并且可以通过在组之间移动元素来进行调整，直到达到平衡。 当总和为奇数或只有一个元素无法拆分时，就会出现唯一的结构性不可能性，这充分描述了失败案例的特征。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    
    if n <= 1:
        print("N")
        return
    
    if total % 2 != 0:
        print("N")
        return
    
    print("S")

if __name__ == "__main__":
    solve()
```故意将实现最小化，因为该解决方案减少到两次检查。 我们首先计算线性时间内的总和。 然后我们立即处理只有一个包的退化情况，因为无论值如何，拆分都是不可能的。 最后，我们检查总和的奇偶性。 接受至少包含两个元素的任何偶数总和。 

Python 中不存在整数溢出的边界问题，因为整数是无界的。 检查顺序仅对提前退出效率重要。

 ## 边缘情况

 单元件情况是唯一超越宇称的结构上不可避免的故障。 用于输入`1\n42`，该算法计算 sum = 42（偶数），但由于以下原因立即拒绝`n <= 1`。 这符合两个参与者必须接收非空组的要求。 

奇数总和，例如`3\n1 2 2`在奇偶校验阶段被拒绝，因为不存在将整数划分为相等的两半。 

大型均匀阵列，例如`6\n5 5 5 5 5 5`通过两项检查并被接受。 尽管没有明确构造分区，但该条件确保了可行性，因为元素可以分为基数和总和相等的两组。 

这些情况共同涵盖了所有故障模式：奇偶校验违规和元件数量不足。
