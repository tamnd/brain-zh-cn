 ## 解决方案
 ## 问题理解

 我们被要求构造一个精确的序列$N$正整数，使得序列严格递增，并且在所有此类序列中，我们想要总成本最小的序列。 

成本结构是关键部分。 每个整数都通过其二进制表示进行评估。 每一位位置$i$有固定成本$C_i$。 如果一个数有位$i$设定，它贡献$C_i$到这个数字的成本。 因此，一个数字的成本只是它所包含的位位置的成本之和。 位之间没有交互，成本中没有进位效应，并且不依赖于位所存在的数值。 

序列约束“严格增加正整数”仅强制所有选定的整数都是不同的并且可以按值排序。 由于可以对任意一组不同的正整数进行排序，因此排序约束并不限制我们可以选择哪些数字组，只是我们不能重复数字并且必须避免零。 

所以任务减少为选择$N$不同的非零二进制掩码$M$位，最小化其位成本总和。 

这些限制使这变得有趣。$M$可以大到 1000，所以可能的数字的宇宙是巨大的，最多可达$2^M - 1$。 然而，$N \le 100$，所以我们只需要指数大小的空间中的 100 个最便宜的对象$M$。 任何试图枚举所有子集的方法都是不可能的。 即使对所有位掩码进行动态编程也是不可行的，因为$2^M$状态空间。 

一个天真的尝试是考虑生成所有子集成本并选择最小的$N$。 这会立即失败，因为子集的数量呈指数增长$M$，甚至存储它们也是不可能的。 

第二个天真的想法是贪婪地选择具有最小成本模式的位或数字，但这失败了，因为子集以组合方式相互作用：早期组合稍微昂贵的位可以稍后产生更便宜的多位子集，因此局部决策不能保持全局最优性。 

一个微妙的边缘情况是空子集。 它的成本为零，并且它始终是最佳候选者，但它对应于数字零，这是不允许的，因为所有整数都必须是正数。 任何正确的解决方案都必须明确地将其排除在考虑之外。 

## 方法

 问题的结构是：每个数字是最多 1000 个独立项（比特）的子集，子集的成本是项权重之和。 我们想要$N$最小子集和，不包括空子集。 

这是一个经典的“独立权重的 k 个最小子集和”问题。 蛮力方法枚举了所有子集$M$位，计算它们的成本，对它们进行排序，然后选择第一个$N$。 从概念上讲，这是可行的，因为每个子集都是独立的，并且其成本很容易计算。 失败点是指数爆炸：$2^{1000}$子集远远超出任何限制。 

关键的观察是我们不需要所有子集。 我们只需要第一个$N$， 在哪里$N \le 100$。 这使我们能够在逐个扫描位的同时仅保留一小部分最佳候选者。 每个位要么出现在子集中，要么不出现，添加一位会增加成本$C_i$。 这相当于重复合并两个排序列表：现有子集总和，以及这些总和加上新的权重。 

我们没有显式存储所有子集，而是维护当前最佳子集的列表$N$子集总和。 当我们用成本处理一个新位时$w$，每个现有子集总和$x$可以产生一个新的候选人$x + w$。 我们合并旧列表和移位列表，只保留最小的$N$结果。 对所有位重复此操作可构建最佳效果$N$子集总和。 

由于所有成本都是非负的，因此当我们扩展可能性时，子集和是单调增加的，并剪枝为$N$元素永远不会丢弃后来可能成为较小结果一部分的东西。 

最后，我们丢弃空子集并获取下一个$N$价值观。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（所有子集）|$O(2^M \cdot M)$|$O(2^M)$| 太慢了|
 | 增量 k 最佳子集 DP |$O(M \cdot N)$|$O(N)$| 已接受 |

 ## 算法演练

 我们将每个位位置视为一个具有权重的独立项$C_i$。 每个子集对应于选择其中一些项目，其成本是所选权重的总和。 

## 算法演练

 1. 从表示“不选择任何内容”的单个子集开始，成本为 0。在我们考虑任何位之前，这充当身份状态。 
2. 维护清单`dp`只存储最小的$N+1$到目前为止看到的子集成本。 我们保留$N+1$而不是$N$因为我们稍后必须丢弃空子集。 
3. 对于每个位位置$i$，读取其成本$C_i$。 将其视为可以包含或排除在我们已经构建的任何子集中的项目。 
4. 通过采用中的每个值构建一个新的候选列表`dp`并且还添加$C_i$到它。 这代表不使用该位或使用该位的所有子集。 
5.合并原来的`dp`和移动后的列表，对它们进行排序，只保留最小的$N+1$价值观。 这确保我们只保留最有希望的子集成本。 
6. 对所有位位置重复此过程。 
7.处理完所有位后，去掉值0（对应空子集）并求和最小的$N$剩余值。 

合并起作用的原因是在处理第一个之后$i$位，`dp`包含仅使用这些位即可实现的最小可能子集和。 当我们引入一个新位时，每个有效的新子集要么是旧子集，要么是旧子集加上该位，因此合并会耗尽所有可能性，而不需要显式子集枚举。 

修剪步骤是安全的，因为所有成本都是非负的。 不属于当前最小子集的任何子集$N+1$以后不能变小，因为未来的操作只会添加非负值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    C = list(map(int, input().split()))

    dp = [0]

    for w in C:
        new = dp + [x + w for x in dp]
        new.sort()
        if len(new) > N + 1:
            new = new[:N + 1]
        dp = new

    # remove empty subset
    dp = [x for x in dp if x != 0]

    print(sum(dp[:N]))

if __name__ == "__main__":
    solve()
```该代码维护最佳子集和的动态列表。 该列表始​​终代表使用处理后的位可实现的最小成本。 每次迭代都会复制当前状态并增加权重，合并两种可能性，并截断以仅保留最相关的候选者。 

最后的零过滤确保我们不会意外地包含无效的空子集。 由于零最初总是最小的元素，因此在求和之前它自然会被删除。

 ## 边缘情况

 空子集是主要的结构边缘情况。 它总是以成本为0的初始状态出现，并且在构建过程中始终是最小值。 该算法故意将其带入中间状态，因为需要生成正确的超集组合，但在产生最终答案之前将其删除。 例如，如果$M = 1$和$C = [7]$，中间状态变为$[0, 7]$。 去除零后，唯一有效的序列元素是 7，它匹配唯一可能的正整数。 

另一个微妙的情况是多个不同的子集产生相同的成本。 当几个位具有相同的值时，这种情况经常发生$C_i$。 该算法保留重复项`dp`，这是必要的，因为每个代表不同的子集，并且我们可能需要多个相同的成本才能达到$N$有效的不同数字。
