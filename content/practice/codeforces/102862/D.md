 ## 解决方案
 ## 问题理解

 我们得到一个小写英文字符串。 我们希望将其切割成尽可能多的连续块。 仅当一个片段包含至少一个元音和至少一个辅音时，才被视为有效单词。 输出是可以覆盖整个字符串的有效片段的最大数量。 如果连一个有效的棋子都无法组成，那么答案就是零。 

字符唯一重要的属性是它们的类型。 一个字符是元音之一`a, i, o, u, e, y`，或者它是一个辅音。 字母的位置对于构建分区很重要，但可能的片段数量仅取决于存在多少元音和辅音。 

字符串长度可以达到$10^5$。 这排除了尝试所有可能的切割位置集，因为分区的数量呈指数增长。 甚至一个$O(n^2)$与简单的线性扫描相比，动态编程方法是不必要的并且太慢。 预期的解决方案应该检查每个字符恒定的次数，给出一个$O(n)$算法。 

第一种边缘情况是字符串仅包含一种类型的字符。 例如：```
Input:
3
aaa

Output:
0
```有元音但没有辅音，因此不存在有效的单词。 仅计算元音并除以某个值的解决方案将错误地产生肯定的答案。 

另一种边缘情况是一种类型的数量远小于另一种类型的数量：```
Input:
7
aaabbbb

Output:
3
```有三个元音和四个辅音。 我们可以创建三个有效单词，但不能创建四个，因为每个单词都需要一个元音。 限制资源是较小的计数。 

最后的边界情况是两种类型恰好出现一次：```
Input:
2
ab

Output:
1
```整个字符串已经是一个有效的单词。 尝试在每个可能的位置进行分割会产生无效的单字符片段。 

## 方法

 自然的暴力方法是尝试字符串的每个可能的分区，并检查每个结果片段是否同时包含元音和辅音。 这是正确的，因为它检查每个可能的答案，但长度字符串的分区数$n$是$2^{n-1}$，因为相邻字符之间的每个间隙都可以包含剪切或不包含剪切。 为了$n=10^5$，这是完全不可能的。 

更好的尝试是从左到右贪婪地构建单词。 然而，关键的观察结果是我们实际上不需要关心切割的确切位置。 每个有效单词至少包含一个元音和至少一个辅音。 如果有$v$元音和$c$辅音，没有解决方案可以有超过$\min(v,c)$因为每个单词都需要两组中的一个字符。 

剩下的问题是这个上限是否总能达到。 如果元音和辅音都存在，我们可以重复地将稀缺类型与另一种类型的字符配对，同时保留原始顺序。 更常见类型的额外字符可以简单地附加到现有单词上。 这意味着如果元音是限制资源，则每个可用的元音都可以参与单独的单词，并且当辅音较少时，相同的论点也适用。 

因此，问题归结为计算两个字符类别。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 统计字符串中出现了多少个元音，以及字符串中出现了多少个辅音。 答案只能取决于这两个数量，因为每个单词至少需要每个类别中的一个字符。 
2. 如果任一计数为零，则输出`0`。 有效的单词需要两种类型，因此字符串无法分区。 
3. 否则，输出两个计数中较小的一个。 这是最大可能的单词数，因为每个单词消耗一个元音和一个辅音。 

为什么它有效：

 最大单词数不能超过元音数或辅音数，因此不能超过$\min(v,c)$。 如果两个类别都存在，则可以将较小的组分配给每个单词一个字符，而可以将较大组中的所有剩余字符放入这些单词中而不使它们无效。 因此上限总是可以实现的，答案正是$\min(v,c)$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    vowels = set("aiouey")
    v = 0
    c = 0

    for ch in s:
        if ch in vowels:
            v += 1
        else:
            c += 1

    if v == 0 or c == 0:
        print(0)
    else:
        print(min(v, c))

if __name__ == "__main__":
    solve()
```代码首先存储元音集，因为每个字符分类都是相同的操作。 在扫描期间，它会递增两个计数器之一。 不需要保存有关位置的信息，因为最终答案完全由两个总计决定。 

条件`v == 0 or c == 0`直接处理不可能的情况。 决赛`min(v, c)`是安全的，因为证据表明较小的类别是唯一的限制因素。 

没有索引操作或嵌套循环，因此不存在边界问题或相差一的情况。 Python 整数也避免了溢出问题，尽管计数器最多$10^5$。

 ## 边缘情况

 对于仅包含元音的字符串，例如：```
3
aaa
```算法计数`v = 3`和`c = 0`。 由于没有辅音，零检查触发并且输出为`0`。 

对于仅包含辅音的字符串：```
4
bbbb
```计数器变成`v = 0`和`c = 4`。 同样，没有有效的单词可以包含两个必需的类别，所以答案是`0`。 

对于其中一个类别较小的字符串：```
7
aaabbbb
```扫描发现三个元音和四个辅音。 答案是`min(3, 4) = 3`。 三个单词各自可以接收一个元音和一个辅音，而剩余的辅音则添加到其中一个单词中。 

对于最小的混合情况：```
2
ab
```计数为 1 个元音和 1 个辅音。 算法返回`1`，匹配唯一可能的分区。
