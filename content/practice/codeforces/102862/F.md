 ## 解决方案
 ## 问题理解

 我们有一排`n`方形细胞。 这些细胞之间和周围有`n + 1`边框，每个边框可以是彩色的，也可以是不着色的。 单元格接触其之前的边界和其之后的边界。 对于每个单元格，我们都被准确告知其两个边框中有多少必须着色，这可以是`0`,`1`， 或者`2`。 任务是确定是否存在满足每个单元格的边界颜色。 

输入是一个序列`a`， 在哪里`a[i]`描述了所需的彩色边数`i`第-个单元格。 输出仅是是否有效分配`n + 1`边界国家存在。 

约束条件`n <= 100000`意味着我们不能尝试所有可能的边框颜色。 有`n + 1`边界，每个边界有两个可能的状态，因此强力搜索将检查`2^(n+1)`即使对于几十个细胞来说，这也是不可能的。 该解决方案需要在线性时间内处理数组。 

棘手的情况是由于相邻小区共享边界而引起的。 对一个细胞做出的选择会立即影响下一个细胞。 

例如，对于一个单元格：```
Input:
1
0

Output:
Yes
```两个外边框都可以保持不着色，所以答案是可能的。 假设每个单元格都需要彩色边框的解决方案在这里会失败。 

另一个边界情况是：```
Input:
2
2 0

Output:
No
```第一个单元格要求其两个边框都着色。 这意味着两个单元格之间的共享边框是彩色的。 第二个单元格已经有一个彩色边框，因此它不能以零个彩色边框结束。 矛盾来自于共同的边界。 

第三个常见错误出现在长时间运行时`1`s。 例如：```
Input:
3
1 1 1

Output:
Yes
```边框可以在彩色和无色之间交替。 一种总是为每个选择同一边的贪心方法`1`最终被卡住。 

## 方法

 直接的做法是一一决定每个边界的状态。 由于每个边框都是二进制的，我们可以尝试所有可能的分配并检查每个单元格是否收到所需数量的彩色边。 这是正确的，因为考虑了所有可能的颜色。 然而，有`n + 1`边界、给予`2^(n+1)`作业。 和`n = 100000`，这远远超出了任何时间限制所能承受的范围。 

关键的观察是，这并不是真正的全局搜索问题。 单元格形成一条线，每个单元格仅依赖于两个相邻的边界。 一旦单元格的左边框已知，右边框就会被强制，因为单元格需要固定总数的彩色边框。 

让边框位于单元格之前`i`是`x[i-1]`和它之后的边框`x[i]`。 条件是：```
x[i-1] + x[i] = a[i]
```如果我们选择`x[0]`，确定接下来的每个边界值。 由于第一个边界只能是`0`或者`1`，只有两条可能的路径需要检查。 

对于选定的起始值，我们从左向右移动。 在每个单元格，下一个边界是：```
next_border = required - current_border
```如果这个值不是`0`或者`1`，目前的选择是不可能的。 处理完所有单元格后，最终边框值也会自动有效，因为它是作为序列的一部分生成的。 

暴力方法会失败，因为它会探索所有边界组合。 数组的结构将选择减少到只有两种可能的起始状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 尝试最左边边框的第一种可能的颜色。 它可以是`0`或者`1`。 整个顺序是在这个选择之后确定的，因此检查两种可能性就足够了。 
2. 从左到右扫描单元格，同时存储当前左边框的颜色。 对于当前单元格，计算满足其所需值所需的右边框。 
3.如果计算出的右边界不是`0`或者`1`，拒绝这个起始选择。 边框不能部分着色或具有任何其他状态。 
4. 否则，使用这个新计算的边框作为其左边框移动到下一个单元格。 
5. 如果任一起始选择成功到达末尾，则打印`Yes`。 如果两种选择都失败，则打印`No`。 

为什么它有效：

 扫描期间的不变性是，在处理单元格之前，存储的边框值正是为该单元格左侧选择的颜色。 该算法计算右侧能够满足单元格的唯一可能值。 如果该值无效，则该单元格不存在其他选择，因为双方都已限制为二进制值。 由于第一个边框是唯一的自由决定，因此测试这两种可能性涵盖了每种有效的颜色。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def check(a, first):
    cur = first
    for need in a:
        nxt = need - cur
        if nxt < 0 or nxt > 1:
            return False
        cur = nxt
    return True

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    if check(a, 0) or check(a, 1):
        print("Yes")
    else:
        print("No")

if __name__ == "__main__":
    solve()
```这`check`函数表示最外层左边框的一种可能的颜色。 变量`cur`将与当前单元格共享的边框存储在其左侧。 

对于每个单元格，右边界都是强制的。 如果细胞需要`need`彩色边框和左边框已经做出了贡献`cur`，另一个边界必须做出贡献`need - cur`。 由于边界是二进制的，任何超出边界的值`0`或者`1`立即使该尝试无效。 

main 函数仅运行此模拟两次，一次使用未着色的第一边框，一次使用着色的第一边框。 扫描期间不需要数组，因为只有当前边界状态很重要。 

不存在溢出问题，因为涉及的每个值最多是`2`，并且通过检查两个可能的初始边界来处理边界条件。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 该数组被扫描两次，一次针对每个可能的第一边界状态。 |
 | 空间| O(1) | O(1) | 仅存储当前边界值。 |

 该算法为每个单元执行恒定量的工作。 和`100000`细胞，这很容易满足时间和内存的限制。

 ## 边缘情况

 处理单单元格的情况是因为算法仍然尝试两种可能的外边界值。 对于输入：```
1
0
```开始于`0`给出下一个边界为`0`，这是有效的。 扫描完成并返回`Yes`。 

共享边界矛盾出现在：```
2
2 0
```无论最初的选择如何，第一个单元格都会强制中间边框着色。 那么第二个单元格的颜色边框不能为零。 该算法捕获了这一点，因为所需的下一个边界变为`-1`。 

需要一个彩色面的长序列单元通过强制交替来处理。 为了：```
3
1 1 1
```从未着色的左边框开始创建序列：```
0, 1, 0, 1
```每个单元格只能看到一个彩色边框，因此算法会接受它。 

该方法不需要对需要两个彩色边框的单元格进行特殊处理。 值为`2`只是强制两个相邻边框着色，并且在处理下一个单元格时，任何冲突都会自然出现。
