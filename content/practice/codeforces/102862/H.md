 ## 解决方案
 ## 问题理解

 我们有一棵树，每个顶点都存储两个数字，`a`和`b`。 有趣的值不仅仅是这两个数字，而是它们的差异：$$c_v = a_v - b_v$$从顶点开始的 DFS 步长`v`可以移动到相邻的顶点`u`确切的时间：$$a_v+b_u=a_u+b_v$$重新排列给出：$$a_v-b_v=a_u-b_u$$因此 DFS 只遍历其端点当前具有相同值的边`c`价值。 当一个顶点在 DFS 中完成后，它的`a`值变为`b`，这意味着它的`c`值变为零。 

任务是处理三种类型的操作。 我们可以改变一个顶点`a`value，求一个顶点的当前值`a`值，或者从起始顶点有效地模拟 DFS 过程。 

约束允许最多`5 * 10^5`顶点和查询。 重复扫描整个树或每第三个查询对所有顶点运行一次新的 DFS 的解决方案会太慢。 对于 50 万次操作，我们需要所有 DFS 模拟的总工作量接近线性。 

重要的观察是第三个查询仅更改当前差异的顶点`c`非零且等于起始顶点的差。 一旦这样的顶点被处理，它的差异就变为零。 顶点只能通过类型 1 查询再次变为非零，这只会更改一个顶点。 这给了我们一个摊销界限：实际洪水填充访问的每个顶点要么是最初的非零顶点之一，要么是通过先前的更新变为非零的。 

仔细的实现必须处理起始顶点已经有的情况`a_v=b_v`。 例如：```
1 1
5
5
```来自顶点的第三个查询`1`不应该做任何事情并且价值仍然存在`5`。 尝试搜索差异为零的组件的简单实现可能会浪费时间重复遍历整个零组件。 

另一个边缘情况是包含多个具有相同非零差异的顶点的组件：```
3 1
10 20 30
5 15 25
1 2
2 3
3 1
```差异都是`5`，因此DFS访问了所有三个顶点，运算后的输出为：```
5 15 25
```为了他们的`a`价值观。 仅重置起始顶点的解决方案是不正确的。 

最后一个重要的情况是当单个更新重新连接大型组件时：```
3 2
10 0 0
0 0 0
1 2
2 3
1 2 10
3 1
```更新后，三个顶点都有差异`10`，因此第三个查询必须清除所有三个查询。 算法在遍历时必须始终比较当前的差异。 

## 方法

 直接的解决方案是模拟所描述的DFS。 对于每个类型 3 查询，从请求的顶点开始，递归访问当前差异匹配的邻居，并设置`a_v=b_v`回来后。 这正是该声明所描述的，因此正确性是立即的。 

问题是，如果我们只看树结构，同一个顶点可能会出现在多次 DFS 遍历中。 路径或星形树可以使单个查询触及几乎每个顶点，并且重复多次会导致周围`O(nq)`工作。 

关键的一点是 DFS 具有破坏性。 非零差分分量在处理后消失，因为该分量中的每个顶点都变成差分零。 顶点返回非零差异的唯一方法是类型 1 查询，并且会影响一个顶点。 因此，在整个执行过程中，所有有意义的 DFS 操作可以删除的顶点总数受到初始非零顶点数加上更新次数的限制。 

这使我们能够使用简单的洪水填充方法。 我们不需要复杂的动态连接结构，因为操作本身会破坏它所探索的图的部分。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(n) | 太慢了|
 | 最佳 | O(n + q) 摊销 | O(n) | 已接受 |

 ## 算法演练

 1. 存储当前`a`值和固定值`b`价值观。 对于每三个查询，计算当前差异`a[v]-b[v]`的起始顶点。 

如果该值为零，则 DFS 将仅访问已经满足的顶点`a=b`，因此该操作不会改变任何内容。 我们可以立即跳过它。 
2. 对于非零起始差值，使用堆栈运行迭代 DFS。 保留一个时间戳数组来标记当前洪水填充期间访问的顶点。 

时间戳避免清除完整的`visited`每次查询之前的数组，这会花费`O(n)`即使对于没有任何改变的查询。 
3. 处理顶点时，检查所有相邻顶点。 如果未访问的邻居具有相同的当前差异，则将其压入堆栈。 

相等性检查使用当前值`a`，因为 DFS 的先前部分可能已经将顶点更改为`b`。 
4. 从堆栈中取出一个顶点后，设置`a[v]=b[v]`。 

这与原始 DFS 完成该顶点的效果完全匹配。 由于图是一棵树，因此更改已处理的顶点无法创建应该访问的其他路径。 

为什么它有效：

 DFS条件等价于差值相等`a-b`。 因此，原始过程精确访问图形内起始顶点的连通分量，该图形仅包含相等差异之间的边。 该算法执行相同的搜索并对每个访问的顶点应用相同的最终分配。 时间戳仅防止重新访问一次搜索中的顶点，摊销参数证明所有查询的搜索总量与初始活动顶点加上更新的数量呈线性关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = [0] + list(map(int, input().split()))
    b = [0] + list(map(int, input().split()))

    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    seen = [0] * (n + 1)
    timer = 0
    ans = []

    for _ in range(q):
        query = list(map(int, input().split()))
        t = query[0]

        if t == 1:
            v, x = query[1], query[2]
            a[v] = x

        elif t == 2:
            ans.append(str(a[query[1]]))

        else:
            v = query[1]
            diff = a[v] - b[v]

            if diff == 0:
                continue

            timer += 1
            stack = [v]
            seen[v] = timer

            while stack:
                x = stack.pop()

                for y in g[x]:
                    if seen[y] != timer and a[y] - b[y] == diff:
                        seen[y] = timer
                        stack.append(y)

                a[x] = b[x]

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```实施保持`a`可变的，因为类型 1 和类型 3 查询都会更改它。 这`b`数组永远不会改变，因此它是单独存储的。 

洪水填充使用显式堆栈而不是递归。 和`5 * 10^5`顶点，递归 DFS 将超出 Python 的递归限制并存在堆栈溢出的风险。 

循环内的顺序很重要。 指定了一个顶点`a[x]=b[x]`在检查了其邻居之后。 这反映了原始的 DFS，即在探索所有有效子项之后进行分配。 如果分配首先发生，则差异将变为零，并且搜索将错误地丢失信息。 

时间戳技术避免了为每个查询分配或重置大型访问数组的需要。 每个实际的洪水填充仅接触它需要的顶点。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + q) 摊销 | 每个有意义的洪水填充顶点要么最初是非零的，要么是通过更新创建的，并且每个访问的顶点都会扫描其邻接列表一次。 |
 | 空间| O(n) | 树、值、时间戳和 DFS 堆栈都使用线性内存。 |

 约束足够大，任何重复遍历整棵树的解决方案都会失败。 摊余边界使简单遍历符合限制。

 ## 边缘情况

 对于起始顶点`a_v=b_v`，算法计算出的差值为零并立即跳过搜索。 这与真实的 DFS 匹配，因为每个访问的顶点都将以与其开始时相同的值结束。 

对于连通的非零分量，例如：```
3 1
10 20 30
5 15 25
1 2
2 3
3 1
```所有顶点都有差异`5`。 堆栈从顶点开始`1`, 发现顶点`2`和`3`，然后分配他们的每一个`a`价值观`b`。 结果值变为：```
5 15 25
```对于通过更新重新创建的组件，例如：```
3 2
10 0 0
0 0 0
1 2
2 3
1 2 10
3 1
```更新改变顶点`2`所以每个顶点都有差异`10`。 第三次查询从顶点开始`1`，通过等差到达所有三个顶点，并重置所有三个顶点。 该算法处理这个问题是因为它总是读取当前的`a-b`值而不是依赖于任何先前的组件信息。
