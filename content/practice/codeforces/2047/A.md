 ## 解决方案
 ## 问题理解

 阿廖娜围绕中心一块逐层搭建了一个方形拼图。 

第一层仅由中心部分组成，因此包含 1 个图块。 后面的每一层都在前一个拼图周围形成一个完整的方形环。 每天她都会添加一些由数组给出的碎片`a`。 

如果到目前为止组装的零件总数恰好完成了某个方形层，阿廖娜在一天结束时会很高兴。 如果她完成了一层并在同一天立即开始下一层，她会不高兴，因为在当天结束时已经存在未完成的层。 

我们得到每天放置的棋子数量，并且必须计算有多少天正好在层边界处结束。 

关键的观察来自于方形层的几何形状。 完成几层后，组装好的拼图始终是一个完整的正方形。 整理层后总件数`k`是$$1, 9, 25, 49, 81, \dots$$这些正是奇数方块：$$1^2,\; 3^2,\; 5^2,\; 7^2,\dots$$因此，当累计放置的棋子数量为奇数完全平方数时，这一天就是幸福的。 

限制非常小。 每个测试用例最多100天，最多500个测试用例。 即使每天执行少量工作的算法也很容易足够快。 挑战在于识别方形层背后的数学模式。 

一个常见的错误是检查累积的棋子数是否是完全平方数。 只有奇数方块对应于已完成的层。 

考虑：```
1
2
1 3
```累计金额为`1`和`4`。 尽管`4`是完全平方，不是奇数平方，所以第二天不开心。 正确答案是：```
1
```另一个容易犯的错误是，在当天添加的过程中，只要完成了一层，就算一天。 幸福取决于一天结束时的状态。 

例如：```
1
2
1 10
```累计金额为`1`和`11`。 第2天过去了`9`，它完成了一层，但结束于`11`，下一层已经开始。 正确答案是：```
1
```## 方法

 强力解决方案可以直接模拟层大小。 

中心贡献1件。 接下来的几层贡献：$$8,\;16,\;24,\;32,\dots$$因为边长为方环加上的周长$2k+1$是$8k$。 

我们可以继续生成层边界，并在每天之后检查累积的块数是否等于其中之一。 这是正确的，因为层边界正是完成每个环后的总数。 

尽管这适用于给定的约束，但它依赖于显式生成几何图层信息。 

更优雅的观察是，完成的层总是形成奇数边长的正方形：$$1 \times 1,\; 3 \times 3,\; 5 \times 5,\; 7 \times 7,\dots$$因此，完成层的总块数为：$$1^2,\;3^2,\;5^2,\;7^2,\dots$$问题立刻变成：

 “计算有多少个前缀和是奇完全平方数。”

 由于最大可能的总件数仅为$100 \times 100 = 10000$，我们可以预先计算 10000 以内的所有奇数平方并检查集合中的成员资格。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n + 层数) | O(1) | O(1) | 已接受 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 预先计算 10000 以内的所有奇完全平方并将它们存储在一个集合中。 
2. 对于每个测试用例，初始化一个运行前缀和`s = 0`。 
3. 按顺序处理日期。 
4. 将当天放置的件数添加到`s`。 
5. 检查是否`s`属于奇数平方的集合。 
6. 如果是，则增加答案，因为谜题恰好在完成的层处结束。 
7. 处理完所有日期后，输出答案。 

### 为什么它有效

 完成的拼图层总是形成边长为奇数的正方形。 完成第一层后我们有$1^2$件，完成第二层后我们有$3^2$件，完成第三层后我们有$5^2$件等。 

相反，每个奇数方块对应于完全完成的层集合。 因此，当放置的棋子的累积数量等于奇数平方时，这一天就是快乐的。 该算法精确计算这些天数，因此不会多算或少算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# all possible totals are at most 100 * 100 = 10000
odd_squares = set()
k = 1
while k * k <= 10000:
    odd_squares.add(k * k)
    k += 2

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    s = 0
    ans = 0

    for x in a:
        s += x
        if s in odd_squares:
            ans += 1

    print(ans)
```第一部分预先计算可能作为前缀和出现的每个奇数平方。 由于棋子总数永远不会超过 10000，因此只需要达到该限制的奇数方格。 

对于每个测试用例，变量`s`存储迄今为止组装的累积件数。 处理完一天后，我们检查这个累计总数是否等于奇数平方。 

使用集合使得成员资格检查平均时间恒定。 不需要平方根计算，这使得实现简单并避免任何浮点问题。 

边界条件很简单。 第一天总是贡献一块，所以第一个前缀和是`1`，它被正确识别为第一个奇数方块。

import io

def run(inp: str) -> str:

```前缀和是`1`和`11`。 第 2 天期间，运行总计经过`9`，但这一天结束于`11`。 幸福只取决于一天的最终状态。 自从`11`不是奇数平方，该算法仅计算第一天：```
