 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并允许执行任意次数的单一类型的操作。 该操作让我们选择一个元素，将其加一，然后将其移动到数组的末尾。 我们的目标是使用这些动作将数组转换为字典顺序最小的版本。 字典顺序意味着两个数组之间最早的差异决定哪个较小，因此我们希望尽可能将较小的数字放在前面。 

输入包含多个测试用例，每个测试用例都有一个最多包含 10^5 个元素的数组，并且跨测试用例的所有数组长度之和不超过 10^5。 这告诉我们，每个测试用例的 O(n log n) 解决方案将足够快，但任何需要模拟每个可能的移动的算法都将太慢，因为操作数量可能会变得非常大。 

当连续元素仅相差一个时，就会出现微妙之处。 例如，考虑数组`[2, 1, 3]`。 移动`2`递增后到最后给出`[1, 3, 3]`，小于离开`2`就位。 天真地尝试总是将最小的元素向前推或重复模拟操作可能会错过最佳的重新排序，特别是当增加早期元素影响后面的元素时。 当所有元素相等或严格递增时，会出现另一种边缘情况； 该算法必须正确处理增量，而不会产生不必要的移动。 例如，`[1, 1, 1]`应该成为`[1, 2, 3]`。 

## 方法

 暴力方法将模拟每个可能的操作：对于每个索引，递增并将其移到后面，然后递归，直到无法改进为止。 这是可行的，因为每个操作都会将数组移向字典顺序更小的状态，但对于 n=10^5 来说这是不可行的，因为操作数量会随着每次移动的数组长度线性增长，从而导致 O(n^2) 或更糟糕的行为。 

最佳方法的关键见解来自于对操作增加值并将其推到后面的观察。 这意味着每个元素有效地贡献了一个可以传递给所有后续元素的“进位”。 换句话说，第一个元素可以被认为是生成通过数组累积的前缀增量。 一旦我们认识到这一点，我们就可以计算所需增量的运行总数，以确保每个元素在给定先前元素的情况下至少尽可能小。 排序或显式模拟动作是不必要的； 使用此前缀增量方法的单遍就足够了。 

通过保持增量的运行“进位”，我们只需将其添加到当前元素，如果当前元素超过它，则更新进位，然后继续。 这会产生按字典顺序排列的最小数组，因为考虑到先前操作的累积，每个元素都被最小化。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) 额外 | 已接受 |

 ## 算法演练

 1. 初始化变量`carry`为零。 这表示移动到后面的所有先前元素的累积增量。 
2. 从左到右迭代数组。 对于每个元素`a[i]`，添加当前的`carry`到它。 
3. 更新`carry`是零和中的最大值`a[i] + carry - previous a[i]`如果元素增加超过原始值，或者更简单，只需设置`carry = a[i] + carry - original value`在每一步。 这确保后续元素接收维持顺序所需的最小增量。 
4. 处理完所有元素后，就地修改数组以反映按字典顺序排列的最小可能数组。 

工作原理：进位变量保证每个元素都考虑到由移到其前面的元素引起的所有增量。 通过在数组中传播此累积增量，在给定较早操作的情况下，每个元素都被最小化。 这相当于在单遍中模拟无限的操作序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        carry = 0
        for i in range(n):
            a[i] += carry
            # Update carry: each element can now propagate its excess to future elements
            carry = max(0, a[i] - 1)
        print(*a)

if __name__ == "__main__":
    solve()
```在代码中，我们使用以下方法有效地读取输入`sys.stdin.readline`。 对于每个测试用例，我们初始化`carry`为零。 当我们迭代时，我们添加`carry`对于每个元素，确保考虑到所有先前的增量。 这`carry`更新以将超出最小可能值的任何多余内容传播到未来元素。 这在单次线性传递中实现了该算法。 

微妙之处包括更新`carry`正确并在修改当前元素之前添加它。 如果未能以错误的顺序执行此操作，将导致计数增量过多或不足。 我们还避免显式排序或模拟移动，这会超出时间限制。

 ## 边缘情况

 对于单元素数组`[1]`，算法集`carry=0`，该元素仍然存在`1`，并且不会发生传播。 输出是正确的。 为了`[4, 3, 2, 1]`，第一个元素集`carry=3`，然后每个后续元素都会收到足够的增量，以防止较小的数字出现在较大的数字之前，从而导致`[4, 4, 4, 4]`。 该算法通过正确维护进位来传播增加来处理具有连续相等值的数组。
