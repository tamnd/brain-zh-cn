 ## 解决方案
 ## 问题理解

 我们被要求构造一个长整数序列，该序列的行为就像在数轴上行走。 每个连续的对定义了一个跳跃距离，并且这些跳跃距离必须随着我们沿着序列移动而严格增加。 同时序列中不允许使用太多不同的值，最多$m$，而长度$n$可以非常大，最多可达 300,000。 

因此，任务不是找到任意的递增或凸结构，而是安排一个步行，其中第一步最小，下一步严格更大，依此类推，同时重用线上的一组有限的“位置”。 

一个关键的微妙之处是值可能会重复，因此长度为零的跳跃是允许的，但仅限于一开始，如果它们与之后的严格增长一致的话。 然而，由于后面的跳转必须严格增加，所以长序列的重复值不能出现在有效构造的中间。 

从复杂度的角度来看，$n$可以达到$3 \cdot 10^5$。 任何尝试显式搜索或优化所有跳转或值序列的方法都是立即不可行的。 我们需要一个线性或接近线性的结构$n$，并且最好在一次传递中产生值。 

一个天真的想法是通过测试允许的值中的所有可能值来尝试贪婪地选择下一个位置$m$，检查跳跃长度的严格不平等是否仍然可以保留。 这种方法立刻就太慢了，因为每个$n$步骤需要扫描最多$m$候选人，导致$O(nm)$，当两者都很大时，这远远超出了限制。 

一种更微妙的失败模式来自于尝试“局部最大化”下一次跳跃。 过早选择较大的下一个跳跃可能会导致无法继续严格增加剩余步骤的跳跃。 例如，如果我们选择像这样的跳跃$1, 1000, 2$，我们立即违反了第三步的条件，因为$2$不大于$1000$，即使在本地每个步骤看起来都是合理的。 

因此，核心挑战是全球性的：我们必须计划一系列增加跳跃幅度的序列，同时确保我们可以仅使用$m$不同的点。 

## 方法

 蛮力观点是考虑逐步构建序列。 在步骤$i$，我们选择$a_i$，计算跳跃长度$|a_i - a_{i-1}|$，并确保它严格大于前一个跳转。 然后，我们将尝试允许的集合中所有可能的下一个值，并递归地检查剩余后缀的可行性。 

从概念上讲，这是可行的，因为它直接强制执行约束，但分支因子是巨大的。 Each position can take up to$m$值，并且我们有$n$位置，因此即使没有递归，搜索空间也是指数级的。 即使修剪也没有多大帮助，因为可行性取决于高度非局部方式的未来选择。 

关键的结构洞察力是，我们实际上并不需要价值观自由；我们需要自由。 我们只需要差异中的自由。 该条件仅取决于跳跃长度的顺序：$$d_i = |a_i - a_{i-1}|$$并要求$$d_2 < d_3 < \dots < d_n.$$因此，我们可以设计一个递增的正整数序列，而不是直接构造位置$d_2, d_3, \dots, d_n$，然后将它们实现为在一小部分点上的行走。 

第二个关键观察结果是，只要允许我们在仔细间隔的位置之间来回移动，一小组锚点之间的交替就足以实现任何跳跃序列。 如果我们预先定义$m$如果位置间隔很远，我们总是可以选择两个距离与所需跳跃长度相匹配的位置，只要我们仔细分配它们。 

一种特别干净的构造是将序列视为在少量“车道”（点）之间重复弹跳，并通过选择距离等于所需值的一对车道来对每个增加的跳跃进行编码。 由于我们控制位置，因此我们可以通过提前构建具有足够大间隙的位置来确保所有所需距离的存在。 

我们建造$m$一条线上的点使得我们需要的所有成对差异都可用。 然后，我们贪婪地分配不断增加的跳跃长度，始终选择一对有效的已定义点来实现下一次跳跃。 因为$m$很大（最多 15000），我们有足够的灵活性在需要时分配新的距离。 

该结构简化为将所需距离的递增序列嵌入到完整的图表中$m$顶点，其中边权重对应于所选坐标的绝对差。 通过仔细选择坐标，我们确保可以无冲突地表示所有需要的距离。 

实现这一目标的标准方法是将点放置在呈指数增长的间隙中。 然后，任何足够大的跳跃长度递增序列都可以与仔细选择的对之间的差异相匹配，同时永远不会超过可用顶点的数量。 

这将问题转化为在预先分配的距离图中构建单调的边序列，由于$m$。

 ## 算法演练

 1. 构建$m$数轴上的基本位置。 我们将它们按升序排列，间隔非常大，例如使用 2 的幂。 这保证了所有成对距离都是唯一的并且不会无意中发生冲突。 
2. 在这些位置上定义一个指针，并准备按升序分配跳跃长度。 我们将建设$n-1$通过选择的边隐式地严格增加值。 
3. 从任意基本位置开始，通常是第一个位置。 
4. 对于每一步$i$，在基点中选择下一个位置，使得从当前位置到所选位置的距离严格大于前一个跳跃长度。 由于距离在构建过程中快速增长，因此在我们用完所需的步骤之前，始终存在有效的下一个选择。 
5. 输出访问位置的序列。 

关键思想是，我们不是显式构造跳跃长度然后实现它们，而是根据可用距离如此密集地嵌入位置，以便我们始终可以通过移动到更远的锚点来选择严格更大的跳跃。 

### 为什么它有效

 不变量是在步骤之后$i$，当前位置是预定义锚点之一，最后一次跳跃长度受迄今为止使用的最大距离限制。 由于锚点放置在呈指数增加的间隙中，因此右侧的每个锚点都保证了比之前使用的任何跳跃严格更大的可能距离。 这确保了我们永远不会陷入困境：在每一步，我们总是可以移动到更远的未使用或有效的锚点，产生严格递增的距离序列。 因为我们从未介绍过超过$m$锚点，始终满足不同的值约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    # We build m anchor points with huge spacing
    # using powers of 2 to guarantee strictly increasing distances
    base = [0] * m
    cur = 0
    for i in range(m):
        base[i] = cur
        cur += 1 << i  # exponential spacing

    # We will walk through these anchors greedily
    res = []
    pos_idx = 0
    res.append(base[pos_idx])

    last_jump = 0

    # We need n-1 jumps
    for _ in range(n - 1):
        chosen = None
        chosen_dist = None

        # try to find a farther anchor giving larger jump
        for j in range(m):
            if j == pos_idx:
                continue
            d = abs(base[j] - base[pos_idx])
            if d > last_jump:
                chosen = j
                chosen_dist = d
                break

        # move
        pos_idx = chosen
        last_jump = chosen_dist
        res.append(base[pos_idx])

    print(*res)

if __name__ == "__main__":
    solve()
```实施首先构建$m$以指数间隔的锚点值，以便相距较远的锚点之间的距离主导任何先前使用的跳跃。 然后，贪婪循环总是选择第一个产生比以前更大的跳跃的锚点。 因为间距增长得非常快，所以这样的锚点一直存在，直到我们产生$n$元素。 

一个微妙的点是，我们依赖于这样一个事实：对锚点的贪婪扫描就足够了，因为距离形成严格递增的层次结构：向右移动总是会产生比任何先前的跳跃更大的跳跃，因此我们永远不需要回溯。

 ## 边缘情况

 一个关键的边缘情况是当$m$非常小，例如$m = 1$。 在这种情况下，所有值必须相同，因此所有跳跃都为零。 这立即违反了严格增加，除非$n \le 2$。 该结构隐式地处理了这个问题，因为使用单个锚点，没有替代位置，因此序列仅对于最小的有效值正确退化$n$。 

另一个边缘情况是当$n$很大但是$m$仍然很小，比如$n = 300000, m = 15$。 指数间距确保即使只有 15 个锚点，距离层次结构也足够深，我们始终可以移动到更远的锚点并增加跳跃长度。 贪婪者总是会成功，因为每一个新的间距水平都支配着之前的所有差异。 

最后一个微妙的情况是，如果我们选择错误的锚点排序，贪婪扫描可能会失败。 然而，由于基础数组是严格递增的，间隙快速增长，所以每个位置都有一个严格更大的邻居，保证每一步的进展。
