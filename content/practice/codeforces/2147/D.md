 ## 解决方案
 ## 问题理解

 我们得到一个正整数序列，代表一组带有值的“图块”。 两个玩家，Alice 和 Bob，轮流选择数组中当前存在的数字。 当一个数`x`被选中，玩家获得的分数等于数组中该数字的计数，并且所有实例`x`减少一。 游戏继续进行，直到所有数字变为零。 我们被要求确定爱丽丝和鲍勃的最终得分，假设两人都以最佳方式发挥自己的得分最大化。 

每个测试用例输入最多可以包含 200,000 个数字，并且数字本身可以大到 10^9。 显式执行每个选择和减量的简单模拟是立即不可行的。 如果我们尝试在每一步中将每个数字减一，则操作数量可能与所有数组值的总和成正比，对于最坏情况的输入，该总和最多为 10^14。 这超出了任何实际的运行时间，因此我们需要一种基于计数而不是单个递减进行操作的策略。 

非明显的边缘情况包括所有值都相等的数组、多个小值与单个大值共存的数组以及单元素数组的情况。 例如，如果数组是`[1,1,1]`, 爱丽丝选择`1`立即得3分，一回合结束比赛。 迭代所有值的简单方法可能会错误地尝试减少到​​零以上或错误计算点分配。 

## 方法

 暴力方法会迭代数组，重复选择要递减的值，并更新选择该值的玩家的分数。 它之所以有效，是因为每次移动都被明确定义，但当数组包含非常大的数字时，它就会失败。 例如，选择`10^9`将需要十亿次减量运算，这是不切实际的。 

关键的见解是可以通过按降序对数组进行排序来分析游戏。 每回合，玩家总是会选择最大的可用数字。 因为递减一个数字的所有实例相当于从最高值到最低值按顺序减少数组，所以我们可以通过遍历排序数组并交替轮流来模拟整个游戏。 我们按此顺序累积分数，并按连续的相同数字进行分组。 每个玩家只需轮流挑选最大的剩余数字，并一路累加计数。 这消除了执行每个单独递减的需要，并将时间复杂度降低到元素数量加排序的线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(总和(a_i)) | O(n) | 太慢了|
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 对于每个测试用例，读取数组的大小`n`和数组本身`a`。 
2. 对数组进行排序`a`按降序排列。 这确保了我们总是可以有效地选出最大的剩余数字。 
3. 为Alice 和Bob 初始化两个计分计数器。 让一个布尔标志指示轮到谁了，从 Alice 开始。 
4. 迭代已排序的数组。 当回合属于Alice时，将当前值添加到Alice的分数中； 否则，将其添加到鲍勃的分数中。 
5.处理完每个值后，翻转转弯。 如果连续数字相等，则会在同一回合分配下按顺序处理它们，因为值的每个实例都计入该玩家的分数。 
6. 数组整理完毕后，输出Alice和Bob的累计分数。 

为什么有效：在最佳游戏中总是首先选择最大值，因为它们会立即产生最多的分数。 通过对数组进行排序并按降序迭代，我们保证每个玩家都能捕获其回合中最大数字的所有可用点。 此排序序列中的交替回合精确地模拟了递减游戏，而无需显式更新数组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort(reverse=True)
        alice = 0
        bob = 0
        for i, val in enumerate(a):
            if i % 2 == 0:
                alice += val
            else:
                bob += val
        print(alice, bob)

if __name__ == "__main__":
    main()
```为了提高效率，代码首先使用快速 I/O 读取所有输入。 按降序对数组进行排序允许我们直接模拟最佳移动。 使用`enumerate`模 2 优雅地交替转弯，无需额外的标志。 单元素数组或相等数等边界条件由基于索引的轮分配自动处理。 我们从不尝试减少超过零，因此不需要额外的检查。

 ## 边缘情况

 对于单元素数组`[1]`，Alice 选 1 并得分 1，Bob 得分 0。算法自动将第一个索引分配给 Alice。 为了`[1,1,1,1,1]`，排序后的数组是相同的，并且交替索引给出 Alice 3 和 Bob 2，正确地建模最佳回合。 对于非常大的数字，例如`[10^9, 10^9]`，排序和索引确保Alice和Bob各拿一个，评分`10^9`每个都不执行任何十亿步递减。 该方法凭借排序迭代自然地处理所有边缘情况。
