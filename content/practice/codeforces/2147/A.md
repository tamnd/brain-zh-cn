 ## 解决方案
 ## 问题理解

 我们处于一个从原点开始的二维网格上$(0, 0)$并想要达到一个目标$(x, y)$。 运动受到两种方式的限制。 首先，我们交替轴：第一步沿着$x$，第二个沿$y$，第三个$x$再次，依此类推。 其次，每一步的长度必须严格大于前一步的长度。 每一步必须移动正整数距离。 

输入给出多个测试用例，每个测试用例提供一个目标$(x, y)$。 每种情况的输出是在这些规则下达到目标所需的最少步骤数，或者$-1$如果不可能的话。 

约束条件允许$x$和$y$最多$10^9$直至$10^4$测试用例。 这排除了任何尝试枚举每个可能的步骤序列的解决方案。 简单的递归或回溯方法会生成指数数量的序列，这太慢了。 挑战在于识别步长的结构：每个坐标必须通过分配给交替轴的严格递增的整数序列来到达。 

边缘情况包括以下情况$x$或者$y$小于步骤序列所需的值。 例如，$(1,1)$是不可能的，因为搬家后$1$沿着$x$，下一个$y$步骤必须至少为$2$，超出目标。 同样，像这样的目标$(5,4)$需要仔细分割步骤，否则序列不能满足严格增加的长度。 

## 方法

 蛮力方法将尝试所有递增正整数的序列$x$和$y$或者，检查总和是否与目标匹配。 对于长度序列$k$, 大致有$O(k!)$序列。 即使对于小$k$，这增长得太快并且对于$x, y$最多$10^9$。 

关键的见解是问题简化为找到最少的步骤数$k$使得适当的整数子集的总和等于$x$和$y$，尊重交替顺序。 我们可以使用第一个的最小可能和来形式化它$m$整数：$1 + 2 + ... + m = m(m+1)/2$。 

如果$k$是总步数，让$k_x$是前进的步数$x$和$k_y$沿着$y$， 和$k_x = \lceil k/2 \rceil$和$k_y = \lfloor k/2 \rfloor$。 可能的最小总和为$k_x$一步一步$x$是$k_x(k_x + 1)/2$，类似地对于$y$。 如果$x$小于这个总和或者$y$小于其对应的和，则该序列不存在。 否则，可以通过增量分配步长以精确匹配总和来构造有效序列，从最小序列开始并根据需要调整最大步长。 

这一观察将问题简化为一个简单的检查：从$k = 1$， 增加$k$直到最小总和为$x$和$y$内可以实现$k$步骤。 如果$k$增长太大而无法满足总和，则目标无法实现。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^k) | O(2^k) | O(k) | 太慢了 |
 | 贪婪/建设性| 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.对于每个测试用例，提取目标坐标$(x, y)$。 确保$x \le y$简化推理； 否则交换轴。 这是对称的，因此它不会改变答案。 
2.如果$x = 0$或者$y = 0$， 输出$-1$，因为每个步骤必须是正整数。 同样，如果$x > y$交换后，我们继续使用较小的坐标$x$。 
3. 步数统计$k = 1, 2, 3, ...$, 计算$k_x = \lceil k/2 \rceil$和$k_y = \lfloor k/2 \rfloor$。 这些代表了步骤的数量$x$和$y$分别。 
4. 计算可达到的最小总和$x$和$y$使用第一个$k_x$和$k_y$整数：$min_x = k_x(k_x + 1)/2$,$min_y = k_y(k_y + 1)/2$。 如果$x < min_x$或者$y < min_y$, 增量$k$并重复。 
5. 检查目标和最小总和之间的差异是否可以分布在最大步长中，而不违反严格递增规则。 为了$x \le y$，这总是可以使用贪婪赋值：从序列开始$1..k$并调整最大步长。 
6. 第一个$k$满足这些条件就是最少的步骤数。 如果没有这样的$k$存在到实际界限（例如，当$k(k+1)/2$超过$x+y$）， 输出$-1$。 

**为什么它有效：** 不变量是严格递增的长度序列的最小可能总和$m$是$m(m+1)/2$。 任何达到目标的严格递增的正整数序列必须至少匹配该总和。 通过逐步增加$k$并计算$k_x$和$k_y$，我们保证步数最少，调整最大步数可以精确匹配目标。 交替步长约束本质上是通过将序列分为奇数步和偶数步来强制执行的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x, y = map(int, input().split())
        if x > y:
            x, y = y, x  # ensure x <= y

        ans = -1
        for k in range(1, 100):  # small bound; solution always fits under 100 steps
            kx = (k + 1) // 2
            ky = k // 2
            min_x = kx * (kx + 1) // 2
            min_y = ky * (ky + 1) // 2
            if x >= min_x and y >= min_y:
                diff_x = x - min_x
                diff_y = y - min_y
                if diff_x <= ky and diff_y <= kx:  # can adjust largest steps without conflict
                    ans = k
                    break
        print(ans)

if __name__ == "__main__":
    solve()
```该代码首先标准化坐标，以便$x \le y$，然后迭代潜在的步数。 对于每位候选人$k$，它计算最小总和$x$和$y$。 如果可以通过该步数达到目标，则会打印$k$。 100 的界限来自于前 100 个整数之和为 5050，远远超过了大多数实际的最低要求$x, y \le 10^9$。
