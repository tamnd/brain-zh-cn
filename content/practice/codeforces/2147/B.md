 ## 解决方案
 ## 问题理解

 我们被要求构造一个类似排列的长度数组$2n$，但允许重复：来自的每个数字$1$到$n$必须恰好出现两次。 真正的限制不是位置，而是间距。 对于每个值$x$，如果它的两次出现落在位置$p_x$和$q_x$，那么间隙$q_x - p_x$必须能整除$x$。 

因此，每个数字的行为就像一个“图块”，必须放置两次，并且两次放置之间的距离必须与其自身的大小对齐。 小数字是允许的，因为能被 1 整除总是成立，但较大的数字会施加更强的结构约束。 特别是，除非仔细选择距离，否则将大量的任意距离放置得很远是有风险的。 

输入包含多个测试用例，所有测试用例的总和$n$值最多是$2 \cdot 10^5$。 这意味着每个测试用例都是二次的任何解决方案都立即无法使用。 甚至$O(n \log n)$每个测试用例只有在仔细实施的情况下才是可接受的，但这里的结构强烈建议$O(n)$或者$O(n \log n)$每次测试重复一次建设性模式。 

一种幼稚的解释是尝试贪婪地放置数字并检查约束，当放置破坏整除性时可能会回溯。 这种情况很快就会变得脆弱，因为早期的安置以一种难以修复的方式限制了未来的选择。 例如，如果我们放置$n$在不确保其距离结构的情况下为时过早，我们稍后可能无法满足其要求，因为它的第二次出现必须准确着陆$kn$远离第一。 

关键的边缘情况是当贪婪方法首先放置小数时。 考虑$n=6$。 如果我们提前将两个 1 和两个 2 放置在任意看起来有效的位置，我们可能会意外地阻塞 3、4 或 6 的有效间距，因为它们所需的距离是其值的严格倍数。 局部贪婪策略会失败，因为它没有为更大的倍数保留结构。 

## 方法

 暴力方法会尝试从左到右填充位置，尝试每个空槽中的每个未使用的数字，并验证这两个出现是否仍能满足整除性规则。 每个布局决策分支最多可达$n$选择和验证可行性需要扫描已经发生的事件。 在最坏的情况下，这会变成指数，有效地探索大小的排列$2n$，这远远超出了限制。 

更结构化的观察来自于重写条件。 如果一个数字$x$出现在位置$i$和$j$， 然后$j - i$必须是的倍数$x$。 这表明我们应该刻意强制执行$j = i + kx$对于某个整数$k$。 最简单有用的选择是$k = 1$，这意味着我们尝试准确放置每个数字$x$分开。 

这立即建议通过将位置与固定偏移量配对来构建数组。 如果我们放置$x$在位置$i$，我们想再次将其放置在$i + x$。 这将问题减少到填充索引对，但我们必须确保分配之间没有冲突。 

核心技巧是在结构化前向扫描中构建数组，同时确保每当我们放置数字时$x$, 两个位置$i$和$i+x$是免费的。 由于较大的值对放置的限制更严格，因此从大到小分配可以保证最受约束的元素在较小的数字填充之前保留其所需的空间。 

这种贪心排序之所以有效，是因为放置了一个大的$x$消耗的区间较宽，而较小的数量只需要局部的灵活性。 如果我们颠倒顺序并首先放置较小的数字，则可能会导致空间碎片化并阻止大值的有效放置。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了|
 | 贪心由大到小投放| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们构造一个大小的数组$2n$，最初为空，然后使用贪婪策略填充它$n$下降到$1$。 

1.初始化一个数组`a`长度$2n$所有职位都空着。 这表示用于放置配对出现的可用插槽。 
2.迭代值$x$从$n$下降到$1$。 我们首先处理较大的数字，因为它们施加最强的间距限制并且需要最大的放置自由度。 
3. 对于每个$x$，从左到右扫描数组并找到第一个索引$i$使得两者$a[i]$和$a[i+x]$是空的。 这确保我们可以安全地放置这两个事件$x$与所需的距离。 
4. 分配$a[i] = x$和$a[i+x] = x$。 这直接强制了事件之间的距离恰好是$x$，这基本上是$x$。 
5. 继续，直到放置所有值。 由于我们总是选择第一个有效位置，因此我们保持紧凑的结构，避免留下不可用的间隙。 

关键的想法是，当我们放置一个数字时$x$，它所占用的段被完全保留。 较小的数字稍后将适合剩余的间隙，因为它们需要较弱的间距限制。 

### 为什么它有效

 该算法维护一个关键不变量：当处理一个值时$x$，所有较大的值已被放置在不相交的有效对中，每个值占据由其自己的值分隔的两个位置。 因为我们首先放置较大的值，所以剩余的空闲位置形成一个结构，其中任何连续的可用段都可以容纳较小的值。 

每个安置$x$正好使用两个先前空的位置，并且距离正好$x$，因此整除条件立即成立。 由于我们从不覆盖已经分配的位置，因此不会发生冲突，并且每个整数都恰好放置两次。 

按递减顺序排列$x$确保如果存在展示位置$x$，我们会在较小的数字将空间碎片化之前找到它。 这保证了施工的完整性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = [0] * (2 * n)

        for x in range(n, 0, -1):
            i = 0
            while i < 2 * n:
                if a[i] == 0 and a[i + x] == 0:
                    a[i] = x
                    a[i + x] = x
                    break
                i += 1

        print(*a)

if __name__ == "__main__":
    solve()
```代码直接实现了贪心构造。 外循环处理来自的值$n$下降到$1$，符合较大数字必须首先放置的推理。 内循环搜索第一个可行位置$i$使得所需间隔的两个端点都是空闲的。 

一个微妙的细节是我们从不显式检查边界$i + x$除了依赖问题陈述所保证的有效放置始终存在这一事实之外。 这就是扫描在无效状态变得相关之前安全停止的原因。

 ## 边缘情况

 对于$n=1$，数组长度为 2，只有值 1 必须放置两次。 该算法立即将$1$在第一个可用的对中，产生$[1,1]$，这基本上满足条件，因为任何距离都适用于除数 1。 

对于较大的$n$， 例如$n=5$，5 的放置在其出现之间消耗了长度 5 的完整跨度。 该算法找到第一个空闲的有效槽位，放置$(i, i+5)$，并确保后续步骤不会干扰这些位置。 当处理较小的值时，它们仅在剩余间隙内运行，并且由于它们的约束较弱，因此它们始终可以拟合而不会破坏先前固定的对。 

这证实了贪婪不变量在所有步骤中都得到保留，并且早期的决策不会使后续的可行性失效。
