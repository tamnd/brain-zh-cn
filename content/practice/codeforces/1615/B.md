 ## 解决方案
 ## 问题理解

 我们给出了许多测试用例，每个测试用例都描述了一个连续的整数数组$l$到$r$。 该数组不是任意的，它始终是一个没有间隙的完整区间。 我们的操作是从该数组中删除元素，删除后我们计算剩余数字的按位与。 目标是删除尽可能少的元素，以便最终的 AND 严格非零。 

非零 AND 意味着存在至少一个位位置，使得每个剩余的数字都设置了该位。 换句话说，删除后，所有选定的数字必须共享至少一个公共设置位。 

查询数量方面的限制很大，最多可达$10^4$，并且范围端点达到$2 \cdot 10^5$。 这立即表明任何解决方案都必须在每个测试用例中接近线性或在值范围内对数。 每个时间间隔内的二次甚至幼稚的每个元素检查策略都会太慢。 

当间隔很小时或者当它包含二进制形式非常多样化的数字时，就会出现微妙的边缘情况。 例如，在$[1, 2]$，AND 为零，但仅保留一个元素就已经给出了非零结果。 另一方面，在像这样的间隔$[4, 5]$，两个数字共享允许保留两者的位模式，因此不需要删除。 这种对比表明该结构完全取决于间隔内的共享设置位。 

一个天真的错误是认为我们应该计算整个区间的 AND，然后以某种方式“修复”它。 这会失败，因为一旦全局 AND 中的某个位为零，仍然可以保留该位出现在所有剩余数字中的子集。 

## 方法

 暴力策略会尝试区间的所有子集$[l, r]$，计算每个子集的按位与，并跟踪与非零的最大子集。 这原则上是正确的，因为它直接对条件进行建模，但子集的数量是$2^{(r-l+1)}$，即使对于大小为 30 的间隔也是不可行的。甚至检查 200 个元素间隔的所有子集也是完全不可能的。 

关键的观察结果是，仅当每个选定元素中存在至少一个设置的位位置时，子集上的按位 AND 才为非零。 这就把问题变成了选择位位置$b$，然后只保留数字$[l, r]$那些有一点$b$放。 对于每一位，我们可以计算区间中有多少个数字包含它。 如果我们修复一下$b$，那么我们能做的最好的就是保留所有设置了该位的数字，并删除其余的。 答案是间隔中至少一个数字中出现的所有位的最小删除。 

现在问题归结为计算，对于每一位，有多少个数字$[l, r]$设置了该位。 我们没有迭代每个位的整个间隔，而是使用标准前缀思想：对于每个位，我们可以计算最多有多少个数字$x$使用二进制模式的周期性来设置该位。 每一位$b$以大小块重复$2^{b+1}$， 和$2^b$后面跟着的$2^b$零。 这允许计数$O(1)$每比特，给出一个$O(31)$每个测试用例的解决方案。 

最后，对于每一位，需要删除的是$(r-l+1) - \text{count of numbers with bit b set}$，并且我们取所有位的最小值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集 |$O(2^n \cdot n)$|$O(n)$| 太慢了 |
 | 每一位的位计数 |$O(31)$每次测试|$O(1)$| 已接受 |

 ## 算法演练

 1. 对于每个测试用例，计算间隔的大小：$n = r - l + 1$。 这是我们开始时的元素数量，删除始终与该值相关。 
2. 对于从 0 到 18 的每个位位置（因为$r \le 2 \cdot 10^5$），计算有多少个数字$[l, r]$设置此位。 这是可行的，因为每个整数的二进制表示形式都是独立的，并且每个位在数轴上都遵循重复模式。 
3. 计算最多有多少个数字$x$有一个位设置，使用大小的块结构$2^{b+1}$。 每个完整的块都准确贡献$2^b$那些。 然后通过计算与“on”半个周期的重叠来处理剩余部分。 
4. 对于每一位，计算：$$\text{ones} = \text{count}(r, b) - \text{count}(l-1, b)$$这给出了区间中有多少个数字包含该位。 
5. bit 可以保留的最大子集$b$保证所有元素中的个数恰好是这个数量。 因此该位需要删除的是：$$(r-l+1) - \text{ones}$$6. 对所有位进行最少的删除。 这对应于选择间隔中最“常见”的位。 

### 为什么它有效

 每个有效的最终数组必须至少有一位出现在所有选定的数字中。 修复该位会将间隔分为两组：具有该位的数字和不具有该位的数字。 保留任何没有该位的数字都会立即使 AND 条件无效。 因此，对于任何有效的解决方案，保留的集合必须是共享所选位的数字的子集。 最佳解决方案就是所有位中最大的此类子集，这正是算法评估的内容。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_upto(x, b):
    if x <= 0:
        return 0
    cycle = 1 << (b + 1)
    full = x // cycle
    rem = x % cycle
    ones = full * (1 << b)
    ones += max(0, rem - (1 << b) + 1)
    return ones

t = int(input())
for _ in range(t):
    l, r = map(int, input().split())
    n = r - l + 1
    ans = n
    for b in range(20):
        ones = count_upto(r, b) - count_upto(l - 1, b)
        ans = min(ans, n - ones)
    print(ans)
```功能`count_upto(x, b)`编码比特的周期结构$b$超过整数。 周期长度为$2^{b+1}$，下半部分贡献零，上半部分贡献零。 这避免了显式地迭代范围。 

主循环独立检查每一位，并计算如果该位被选为保证共享位则需要删除多少次。 

一个常见的实施陷阱是忘记处理$l = 1$， 在哪里$l - 1 = 0$。 辅助函数明确地防止非正输入。

 ## 边缘情况

 一种关键的边缘情况是区间仅包含一个数字。 在这种情况下，不需要删除，因为单个元素的 AND 始终是该元素本身，只要数字为正，该元素就不为零。 该算法处理这个问题是因为$n = 1$，对于每一位，删除变成$1 - \text{ones}$，并且数字中恰好有一位将贡献零删除值。 

另一个边缘情况是当$l = 1$。 这里前缀计算需要评估计数$0$。 对于非正输入，辅助函数显式返回零，以确保正确性。 

更微妙的情况是最优解对应于低位而不是高位。 例如，在$[2, 3, 4, 5, 6, 7, 8]$，较高位稀疏设置，但位 0 或位 1 提供更密集的重叠。 该算法独立地正确评估所有位并选择最佳的位，而无需假设位位置的任何单调性。
