 ## 解决方案
 ## 问题理解

 我们有一排塔，每个塔都有一定数量的垂直堆叠的块。 目标是使所有塔的高度尽可能接近。 在任何一天，我们都可以从一座塔上取下一个方块并将其放置在另一座塔上。 排列的丑陋之处在于最高和最矮的塔之间的差异。 我们想要确定在任意数量的块移动后可以实现的最小可能的丑陋。 

输入由多个测试用例组成。 对于每个测试用例，我们得到塔的数量`n`以及那些塔的高度。 每个测试用例的输出应该是一个整数，代表可实现的最小丑陋程度。 

限制是中等的：最多 100 个塔和 1000 个测试用例。 单个塔的高度可达$10^7$。 自从`n`很小，算法是二次的`n`是可行的，但最好采用线性解。 边缘情况包括已经相等的塔楼、只有一栋非常高或非常矮的建筑物的塔楼，以及块的总和不能整除的情况`n`。 一次重复移动一个块的幼稚方法是正确的，但速度不必要地慢。 例如，如果塔是`[1, 2, 3, 1, 5]`，我们不可能总是达到相同的高度，最小的丑陋最终是`1`。 

## 方法

 蛮力方法会尝试反复将块从最高的塔移动到最短的塔，直到无法改进为止。 虽然这最终会收敛，但可能需要最多$O(n \cdot \text{max}(a_i))$操作，当`a_i`可以达到$10^7$。 我们需要一种更明智的方法。 

关键的观察结果是，移动块只会重新分配塔之间的块总数。 让`total = sum(a)`。 如果`total`均匀地除以`n`，我们可以使所有塔都相等，达到丑陋度为 0。如果`total`不均匀划分，那么某些塔一定有`floor(total/n)`块和一些必须有`ceil(total/n)`块。 这两个量之间的差总是`1`，这是可实现的最小丑陋程度。 

这一观察使我们能够在每个测试用例的恒定时间内计算结果：检查总和除以塔的数量并输出`0`或者`1`。 不需要实际的块移动模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n * 最大(a_i)) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，请阅读`n`以及塔楼高度的数组`a`。 
3. 计算所有塔高度的总和。 
4. 计算整数除法`avg = total // n`。 
5. 计算余数`r = total % n`。 如果`r == 0`，总和均分，因此最小丑陋度为`0`。 否则，某些塔楼将不可避免地比其他塔楼高一格，从而使外观至少变得丑陋`1`。 
6. 输出每个测试用例的计算丑陋度。 

该算法之所以有效，是因为块移动操作保留了块的总和。 如果总和不能被平均分配，则最高和最矮的塔最多只能相差一。 这个不变量保证了我们的计算`0`或者`1`总是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    total = sum(a)
    if total % n == 0:
        print(0)
    else:
        print(1)
```该解决方案首先使用有效读取所有输入`sys.stdin.readline`。 对数组求和`a`给出块的总数。 检查整除性`n`直接给出了尽可能最小的丑陋。 支票`total % n == 0`正确处理小和大的和，并且不需要输入数组之外的额外存储。 

## 工作示例

 输入跟踪`[3, 10, 10, 10]`:

 | 步骤| 一个 | 总计 | 总计 % n | 丑陋|
 | ---| ---| ---| ---| ---|
 | 计算总和 | [10, 10, 10] | 30| 0 | 0 |

 所有的塔都已经是平等的； 输出是`0`。 

输入跟踪`[5, 1, 2, 3, 1, 5]`:

 | 步骤| 一个 | 总计 | 总计 % n | 丑陋|
 | ---| ---| ---| ---| ---|
 | 计算总和 | [1, 2, 3, 1, 5] | 12 | 12 12% 5 = 2 | 1 |

 总和`12`除以`5`留下余数`2`。 有些塔必须是`2`块比其他块高，所以最小的丑陋是`1`。 

这些迹线证明了总和决定了可实现的最小差异的不变性。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 每个测试用例 O(n) | 需要为每个测试用例对数组求和一次 |
 | 空间| 每个测试用例 O(n) | 存储塔高度 |

 给定`n <= 100`和`t <= 1000`，最坏情况下的时间约为 100,000 次操作，完全在 2 秒的时间限制内。 在这种规模下，内存使用量可以忽略不计。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        print(0 if sum(a) % n == 0 else 1)

 ## 边缘情况

 For a single operation needed case,`[1, 2]`，总和是`3`。 除以`2`留下余数`1`。 算法输出`1`，正确识别一座塔必须比另一座高。 对于已经平衡的情况`[2, 2, 2]`，总和是`6`，可除以`3`，所以输出是`0`。 两种边缘情况都表明该算法可以正确处理可整除和不可整除的总和，而无需显式的块移动。
