 ## 解决方案
 ## 问题理解

 我们得到的图表一开始是空的，然后随着时间的推移而增长。 每个查询都会在两个顶点之间添加一条新边（红色或蓝色）。 每次添加后，我们都会被问到一个假设的问题：我们可以从当前图中删除多少条边，同时仍然保持所有顶点之间的连接性不变，并且有一个额外的约束，即删除的红色边的数量必须等于删除的蓝色边的数量。 

连接性是在标准无向意义上测量的，忽略颜色。 因此，如果两个顶点在移除之前连接，则它们在移除之后必须保持连接。 这迫使剩余的边仍然包含当前图的每个连接组件的生成林。 

约束很大，查询多达数十万个，因此在每次插入后重新计算连接性或从头开始重新计算所有循环是不可行的。 任何尝试重建生成林或每个查询运行完整 DFS 的解决方案都会太慢，因为这在最坏的情况下会导致二次行为。 

一个微妙的点是，我们没有被要求输出具体的删除策略，只要求输出可删除边的最大数量。 这意味着我们可以根据结构而不是显式构造进行推理。 

一种简单的方法是独立处理每个状态，计算所有桥或生成森林，然后尝试计算有多少条边是“额外的”。 困难在于删除必须按颜色平衡的附加要求。 该约束耦合了本来可以独立移除的边缘。 

一个常见的陷阱是忽略这种耦合并仅计算非树边的数量。 例如，如果除了一条蓝色循环边之外所有边都是红色的，则该图可能有许多冗余边，但如果它破坏了红蓝删除等式，我们就无法将它们全部删除。 

当图形已经连接但所有冗余边都是一种颜色时，会出现另一种失败情况。 例如，假设该图有一个循环，除了一条蓝色边缘外，完全由红色边缘组成。 我们最多可以等量地删除一条红色边缘和一条蓝色边缘，即使在结构上更多的边缘是多余的。 

## 方法

 关键的分离是在结构上对于连接而言必需的边和对于连接而言不是必需的边之间。 在任何图中，如果我们修复连通分量，$n - c$需要边缘来维持每个组件内部的连接性，其中$c$是连接分量的数量。 除此之外的一切都属于循环并且可能是可移除的。 

所以第一个观察结果是“结构冗余”边的数量是$$\text{cycle\_edges} = m - (n - c)$$在哪里$m$是当前图中的边数。 

如果没有颜色约束，答案就是这个循环计数，因为可以删除所有非树边而不会破坏连接性。 

颜色约束引入了全局平衡条件。 让$R$和$B$是循环中红边和蓝边的数量。 如果我们删除一些循环边集，则删除必须满足：$$\text{deleted red} = \text{deleted blue}$$在所有循环边中，如果我们尝试删除所有内容，则不平衡性为$|R - B|$。 我们不能仅使用循环边缘来消除这种不平衡，因为每次删除都会对一侧或另一侧做出贡献。 

因此，最好的策略是删除尽可能多的循环边缘，同时保持最终删除计数平衡。 这意味着我们至少被迫“留下”$|R - B|$循环边缘，否则可以删除。 

这导致最佳计数：$$\text{answer} = \text{cycle\_edges} - |R - B|$$直觉是，一种颜色的每一个额外的剩余都会减少我们可以在循环边缘之间形成的对称删除对的数量。 

暴力方法会在每次查询后显式模拟连接并重新计算循环结构，从而降低成本$O(q(n + m))$，这太慢了。 

优化方法仅维护全局聚合：连接的组件以及红色和蓝色循环边缘之间的差异。 每次插入都是使用 union-find 在接近恒定的时间内处理的，因为我们只需要知道一条边是否创建循环或合并组件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询重新计算（DFS/生成林）|$O(q(n + m))$|$O(n + m)$| 太慢了 |
 | DSU + 周期盘点 |$O((n + q)\alpha(n))$|$O(n + q)$| 已接受 |

 ## 算法演练

 我们在线处理查询，同时维护 DSU（不相交集并）以实现连接。 

1. 初始化 DSU，每个顶点都在其自己的组件中，并以红色和蓝色计数循环边缘。 
2. 为每个查询添加一条边$(u, v)$给定颜色，检查是否$u$和$v$已经在同一个 DSU 组件中。 
3. 如果它们在不同的组件中，则在 DSU 中合并它们。 该边成为生成森林的一部分，并且不是循环边，因此它对可删除边没有贡献。 
4. 如果它们已经在同一个组件中，则这条边形成一个环。 根据颜色增加红色循环计数器或蓝色循环计数器。 
5. 处理完边缘后，计算：

 - 总循环边缘作为红色和蓝色循环计数器的总和
 - 不平衡为$|\text{red\_cycle} - \text{blue\_cycle}|$6. 输出：$$(\text{cycle edges}) - |\text{red cycle} - \text{blue cycle}|$$关键思想是 DSU 隔离连接变化，而循环边缘独立累积。 我们永远不需要明确跟踪哪些确切的边缘形成超出其颜色分类的循环。 

### 为什么它有效

 每个图都可以分解为一个生成森林加上一组循环边。 生成森林是根据选择唯一确定的，但总是包含精确的$n - c$边缘。 可以删除该森林之外的任何边缘，而不会影响连接性。 

唯一剩下的限制是删除必须通过颜色来平衡。 由于只有循环边缘是可移除的，因此问题减少为选择具有相等的红色和蓝色计数的循环边缘的最大多重集。 最佳解决方案消除了所有可能的对，从而使绝对不平衡不可避免。 此不变量成立，因为 DSU 确保每个非循环边都致力于连接并且永远不会进入删除池。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]
        return True

def solve():
    n, q = map(int, input().split())
    dsu = DSU(n)

    red_cycle = 0
    blue_cycle = 0

    for _ in range(q):
        t, u, v = map(int, input().split())
        u -= 1
        v -= 1

        merged = dsu.union(u, v)
        if not merged:
            if t == 1:
                red_cycle += 1
            else:
                blue_cycle += 1

        cycle_edges = red_cycle + blue_cycle
        ans = cycle_edges - abs(red_cycle - blue_cycle)
        print(ans)

if __name__ == "__main__":
    solve()
```DSU 纯粹用于检测边缘在连接方面是否冗余。 如果联合成功，则边缘是生成森林的一部分，并且永远不会直接对答案做出贡献。 

循环计数器将红色和蓝色冗余分开。 最终表达式通过消除不可避免的不平衡来纠正原始周期计数。 

一个微妙的实现点是我们永远不需要存储边或重建图。 一切都简化为每个查询的恒定时间分类。

 ## 边缘情况

 当所有循环边缘都属于单一颜色时，就会出现临界边缘情况。 在这种情况下，DSU 仍然正确识别所有冗余边缘，但不平衡项变得等于循环边缘的数量。 该公式迫使答案为零可删除边缘，因为不可能有相等的红蓝配对。 

另一种情况是循环出现较早，但较晚的边缘合并了先前单独的组件。 这些后来的合并永远不会影响循环计数器，因为 DSU 确保只有组件内的边缘被认为是冗余的，无论插入顺序如何，都可以保持正确性。
