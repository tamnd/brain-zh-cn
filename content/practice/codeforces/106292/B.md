 ## 解决方案
 ## 问题理解

 我们得到了一份公寓清单，每套公寓都有售价和地区标签。 时间分为`t`天，鲍里斯每天最多可以出售一套公寓，或者什么也不做。 目标是选择公寓的子集，并将每个选定的公寓分配到不同的一天，以最大化总收入。 

还有一个额外的约束使得调度变得非常重要。 对于每个地区，如果鲍里斯出售该地区的一套公寓，那么他必须避免过早出售同一地区的另一套公寓。 更准确地说，在任何连续的块中`K`天内，任意固定区域至多可以有一笔销售。 这相当于说，如果同区的两套公寓在几天内出售`d1 < d2`， 然后`d2 - d1 >= K`。 

因此，问题不仅仅是选择最有价值的公寓，还要将它们放在一个时间表上，以便满足地区冷却规则。 

约束条件达到`n, t ≤ 10^5`，这排除了尝试所有布局的任何二次调度或模拟。 任何解必须接近线性或`O(n log n)`。 

当天真的贪婪方法忽略调度结构时，就会出现微妙的故障模式。 例如，如果我们总是选择最昂贵的剩余公寓并任意分配它而不考虑未来的可用性，我们可以很容易地阻止更好的配置。 

考虑这种情况：`t = 3, K = 2`，以及同一地区的两套高价值公寓和另一地区的一套中价值公寓。 如果我们分配第一个选定的公寓太晚，我们可能不会为第二个公寓留下有效的位置，即使不同的排序允许两者都存在。 这表明，如果不仔细放置，仅进行值排序是不够的。 

另一个微妙的案例来自于某个地区的密集冲突。 如果许多公寓共享同一个区域，天真的“全选”策略就会失败，因为间距限制导致无法密集地安排它们。 例如，与`K = 3`，即使我们同区有10套公寓，有很多空闲日，我们也只能挑选大约`t / 3`其中。 

## 方法

 一个蛮力的想法是考虑公寓的所有子集，并尝试使用回溯或动态规划随时间和最后使用的地区位置将它们分配给日期。 这需要跟踪使用了哪些日期并确保每个地区尊重`K`间隙约束。 即使我们只尝试分配一个固定的子集，在最坏的情况下，调度本身也是指数级的，因为每个选定的公寓都可以在许多可能的日子里放置。 和`n = 10^5`，这是远远不可能的。 

关键的观察是天数的具体分配是灵活的。 重要的是是否存在有效的展示位置，而不是我们选择哪个具体的有效时间表。 这表明了一种贪婪的策略：按照价值递减的顺序处理公寓，并尝试尽早将每个公寓放入有效的插槽中。 如果可以安排一套高价值的公寓，我们永远不想拒绝它而选择低价值的公寓，因为所有约束都与价值排序无关。 

这将问题转化为在调度时保持两个约束：每天最多只能容纳一间公寓，并且每个地区都有一个冷却时间，可以将下一个可用日期提前`K`。 

为了支持快速分配，我们维护一个结构，该结构始终在所需的起始点或之后提供最早的空闲日。 这可以使用几天内的不相交集联合结构来实现，其中每一天都指向下一个可用的一天。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(t) | 太慢了|
 | 贪心+DSU调度| O(n α(t)) | O(n α(t)) | O(t) | 已接受 |

 ## 算法演练

 我们按价格降序处理公寓，因为必须优先考虑更高价值的决策，同时仍然尊重可行性限制。 

## 算法演练

 1. 按价格降序对所有公寓进行排序。 这确保了每当我们决定放置公寓时，它都是当时所有剩余选择中的最佳选择。 
2. 维护数组`last[d]`存储我们从地区出售公寓的最后一天`d`。 最初设置所有值，以便每个地区从当天起就可用`1`。 
3. 在数天内维护不相交的集合并集结构`1..t`，其中每一天都指向下一个可用的未使用日期。 这使我们能够快速找到给定日期或之后最早的空闲时段。 
4. 对于按排序顺序的每套公寓，计算其最早的有效销售日：`start = last[b_i] + K`。 这通过建设强制执行地区冷却时间规则。 
5、查询首个免费日的DSU结构`d >= start`。 如果这样的一天存在于`1..t`，将这间公寓指定为当天`d`。 否则，完全跳过公寓。 
6. 当公寓被分配到一天时`d`, 标记日`d`通过将其与 DSU 结构合并来占用`d + 1`，并更新`last[b_i] = d`。 
7. 将赋值存储在初始化为的输出数组中`-1`所有日期，并在指定日期填写所选公寓索引。 

### 为什么它有效

 该算法在整个执行过程中保持两个不变量。 首先，每个分配的日期都是全局唯一的，因为 DSU 总是返回未使用的日期并立即将其从将来的考虑中删除。 其次，每个学区分配都尊重间距，因为我们之前从未允许新的分配`last[b_i] + K`。 

按价值降序处理公寓可确保，如果可以放置高价值公寓，则始终会在任何较低价值的替代方案占用相同的有用时间段之前进行尝试。 DSU 保证我们始终选择最早的可行日期，这样可以避免不必要地向前推进任务，从而保留以后的灵活性。 任何有效的时间表都可以转换为由这种贪婪放置产生的时间表，而不会减少总价值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def find(parent, x):
    if parent[x] != x:
        parent[x] = find(parent, parent[x])
    return parent[x]

def union(parent, x, y):
    x = find(parent, x)
    parent[x] = find(parent, y)

n, K, t = map(int, input().split())

apts = []
for i in range(n):
    a, b = map(int, input().split())
    apts.append((a, b, i + 1))

apts.sort(reverse=True)

parent = list(range(t + 2))
last = {}
ans = [-1] * (t + 1)

def get_next(day):
    if day > t:
        return t + 1
    return find(parent, day)

for a, b, idx in apts:
    prev = last.get(b, 0)
    start = prev + K
    d = get_next(start)
    if d <= t:
        ans[d] = idx
        last[b] = d
        union(parent, d, d + 1)

res_sum = 0
for i in range(1, t + 1):

```实现的核心是按值排序和使用DSU高效跳过已占用天数的结合。 每次我们分配一间公寓时，我们都会立即从可用日期中删除该天，这样以后的分配就不会重复使用它。 

一个微妙的实现细节是我们总是从`last[b] + K`，不是从上次使用的日期加一开始。 这会在调度阶段直接强制执行区域冷却，而不是在分配后尝试验证它。 

输出数组`ans`将天数映射到公寓索引，确保我们可以在线性时间内打印完整的时间表。

 ## 边缘情况

 一种极端情况是许多高价值公寓属于同一地区并且`K`很大。 该算法将仅分配那些符合间距规则的布局，并且 DSU 确保后面的布局正确失败，而不是错误地覆盖较早的布局。 例如，与`K = 3`和天`1..5`，一个地区最多只能安排两次销售，算法自然会强制执行这一点，因为`start`不断增加，而可用天数保持固定。 

另一种极端情况是，如果我们不按价值排序，早期的低价值展示位置可能会阻止高价值展示位置。 排序可确保这种情况不会发生，因为价值较高的公寓总是首先被考虑并占据最早的可行位置。 

最后一种情况是当`t`远大于`n`。 在这种情况下，DSU 的行为仍然正确，因为它只是返回早期的空闲天数，而后面的大多数天数仍然未使用。 如果没有任何特殊处理，时间表自然会变得稀疏。
