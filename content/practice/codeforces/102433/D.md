 ## 问题理解

 我们从一个整数开始\(A\)并想把它变成\(B\)。 在任何时刻，我们都可以将当前值加一，或者当当前值是偶数时将其除以二。 每个操作的成本为 1，因此任务是找到最少的操作数。 

输入包含一对正整数\(A\)和\(B\), 每个最多\(10^9\)。 输出是变化的最短有效操作序列的长度\(A\)进入\(B\)。 官方的样本是\(103 \to 27\)，这需要 4 次操作，并且\(3 \to 8\)，这需要 5 次操作。 citeturn1search17

 的界限\(10^9\)排除模拟每个可能值的算法\(A\)。 线性搜索可能需要大约十亿个状态，这是一种有效的解决方案，应该只需要对数数量的除法。 

在一些边缘情况下，粗心的贪婪实现可能会失败。 如果\(A<B\)， 例如\(3,8\)，答案很简单\(8-3=5\)。 先分裂只会离目标更远，所以总是在可能的情况下试图分裂的策略是错误的。 如果\(A=B\)， 例如\(7,7\)，答案是 0，循环必须在执行不必要的操作之前停止。 如果\(A>B\)和\(A\)是奇数，比如\(7,4\)，划分并不立即合法。 我们首先必须做\(7\to8\)， 然后\(8\to4\)，答案为 2。最后，当除法使值小于\(B\)，我们必须停止除法并使用加法。 为了\(103,27\)，最优序列为\(103\to104\to52\to26\to27\)，所以答案是 4。达到 26 后继续除法的循环将错过最佳值。 引用turn1search0

 ## 方法

 直接的暴力方法是将每个整数视为图状态。 从偶数值\(x\)，最多有两个传出操作，\(x\to x+1\)和\(x\to x/2\)，而仅来自奇值\( the current value \(x\)大于\(B\)，我们最终需要一个部门。 已经在上面的情况下添加一个\(B\)无法完成转换，因此请考虑第一次划分之前发生的情况。 如果\(x\)是偶数，先进行两次加法，然后进行除法，\[
x\to x+1\to x+2\to (x+2)/2,
\]其值相当于先除然后加一，\[
x\to x/2\to x/2+1.
\]第二个版本少用了一个操作。 第一次除法之前的更多添加可以用同样的方式减少。 因此，如果\(x\)为偶数时，最优解的第一个运算是除法。 

如果\(x\)为奇数时，在第一次除法之前需要进行一次加法，否则除法是非法的。 经过一次加法后，该值是偶数，因此我们立即除以。 除法之前的任何附加加法对都可以在除法之后再次移动并保存操作。 

这给出了确定性贪婪过程。 尽管\(A>B\)， 制作\(A\)必要时甚至加一，然后除以二。 立刻\(A\le B\)，划分不再可取。 此时，每个剩余的操作都必须是加法，因此答案增加\(B-A\)。 

蛮力之所以有效，是因为每个操作都可以表示为未加权状态图中的一条边，但它会失败，因为该图可以包含大约十亿个相关状态。 观察到最优路径具有规范顺序，每次划分之前最多添加一次，将搜索压缩为 \(O(\log A)\) 步骤。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 | 最坏情况下的 \(O(A)\) 状态 | \(O(A)\) | 太慢了|
 | 最佳 | \(O(\log A)\) | \(O(1)\) | 已接受 |

 ## 算法演练

 1.如果\(A\le B\)， 返回\(B-A\)。 目标已经等于或高于当前值，加一直接达到。 任何分裂都会导致价值下降，并且至少需要同样多的额外补充才能恢复。 

2. 虽然\(A>B\)，检查奇偶性\(A\)。 如果\(A\)为奇数，加一，增加运算次数。 这是使分割合法化的唯一途径。 

3. 划分\(A\)增加 2 并增加操作次数。 什么时候\(A\)已经是平局了，这是最佳的第一步。 当它是奇数时，前面的添加被强制。 

4. 重复直到\(A\le B\)。 一旦发生这种情况，就停止进行除法。 

5. 添加\(B-A\)到操作计数并返回它。 自从\(A\le B\)此时，只需要添加即可达到目标。 

关键的不变量是，在每次除法之前，算法都使用了使当前值可被 2 整除所需的最小可能加法次数。 对于偶数值，该数字为零，对于奇数值，该数字恰好为一。 任何最佳解决方案都可以转换为具有相同结构的解决方案，而无需增加其长度，因为除法之前的额外添加可以更便宜地移到除法之后。 一旦该值跌至或低于\(B\)，除法不能是最佳延续的一部分，因此最终的直接加法也是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())

    if a <= b:
        print(b - a)
        return

    ans = 0

    while a > b:
        if a & 1:
            a += 1
            ans += 1

        a //= 2
        ans += 1

    ans += b - a
    print(ans)

if __name__ == "__main__":
    solve()
```第一个条件处理整个\(A\le B\)立即办案。 这不仅仅是一种优化：它防止算法除以已经不大于目标的值。 

在循环内部，`a & 1`检查当前值是否为奇数。 如果是的话，`a += 1`使该部门合法化并且只需一次操作即可。 整数除法`a //= 2`则始终有效。 

顺序很重要。 我们必须先将奇数变成偶数，然后再除以它。 我们还检查`a > b`在开始另一次迭代之前，因为除法之后新值可能已经低于目标。 在这种情况下，剩余距离由`b - a`。 

Python整数不会溢出，最大临时值仅为\(10^9+1\)，因此不需要特殊的数字处理。

 ## 边缘情况

 对于\(A=B\), 取输入`7 7`。 初始条件\(A\le B\)为 true，因此算法返回\(7-7=0\)。 无需任何操作。 假设至少需要一项操作的循环会引入不正确的额外步骤。 

为了\(A<B\)， 拿`3 8`。 算法立即返回\(8-3=5\)。 每除一次都会使当前值变得更小，因此无法在直接相加五次的基础上进行改进。 这就是为什么\(A\le B\)case 必须在除法循环之前处理。 

对于高于目标的奇数值，取`7 4`。 由于 7 是奇数，该算法执行\(7\to8\)， 然后\(8\to4\)，进行 2 次操作。 7 不能直接除法，所以强制自增。 除法后结果正好达到目标。 

对于低于目标的划分，取`6 5`。 该算法执行\(6\to3\)，然后停止，因为\(3\le5\)，并添加两次：\(3\to4\to5\)。 总数为 3。再次划分只会增加工作量，因为该值已经低于目标。
