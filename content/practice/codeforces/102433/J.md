 ## 解决方案
 ## 问题理解

 每颗星由三个值描述。 其最大贡献为 (T_i)，每弧度角偏差损失 (s_i) 个贡献单位，其首选方向为 (a_i)。 如果宇宙飞船以角度 (a) 发射，则星 (i) 贡献

 [
 f_i(a)=\max(0,T_i-s_i\operatorname{dist}(a_i,a))。 
]

 距离函数是圆形的，因此角度差始终在 (0) 和 (\pi) 之间。 (a) 方向的总行进距离是所有恒星贡献的总和。 我们需要在整个可能的发射方向上求和的最大值。 

可能有 (10^5) 个星星，因此为每个可能的候选方向评估每个星星是不可行的。 输入包含最多六位小数的实数，但答案必须精确到（10^{-6}），因此实现应使用双精度浮点运算。 重要的约束是 (N=10^5)：(O(N^2)) 算法执行最多 (10^{10}) 颗星评估，远远超出五秒限制所能支持的范围。 我们需要一个 (O(N\log N)) 或类似的有效解决方案。 

有几种循环边界情况可以悄悄地破坏实现。 

第一个是影响区间交叉角 (0)。 例如，```
1
1 1 0.1
```其正贡献区间为 (0.1-1=-0.9) 到 (0.1+1=1.1)。 在圆上，这意味着区间穿过（0），正确答案是（1）。 将角度视为普通线并简单地丢弃负端点会给出接近零的错误斜率。 

第二个是影响力到达相反方向的恒星。 例如，```
1
3.141593 1 0
```(T_i/s_i) 略大于 (\pi)。 恒星在每个方向上都有积极的贡献，其最小近角 (\pi) 和在角度 (0) 处的最大值仍为 (3.141593)。 假设每颗恒星在到达对映方向之前变为零的粗心实现可能会构造无效间隔。 

第三个是(s_i=0)。 例如，```
1
100 0 2
```无论发射角度如何，始终贡献 (100)，因此答案是 (100)。 将 (T_i) 除以 (s_i) 而不处理这种情况会导致除以零。 

最后，几个事件角可能是相同的。 例如，```
2
5 2 1
5 2 1
```有答案（10）。 两颗恒星的最大值都在完全相同的角度，因此该角度的所有斜率变化都必须累积，而不是让一个事件覆盖另一个事件。 

## 方法

 直接的方法是选择发射角度并评估每颗星星。 一个自然的观察是，最佳值出现在某些恒星的首选方向上，因此我们可以评估每个 (a_i) 的总贡献。 这是正确的，因为每个单独的贡献在角度上都是分段线性的，并且其唯一向下的斜率变化发生在其首选方向上。 因此可以在这些方向之一处获取总和的最大值。 

然而，评估每个 (a_i) 的总数仍然需要查看每个 (N) 候选者的所有 (N) 颗星。 在最坏的情况下，这将执行 (N^2=10^{10}) 贡献计算。 蛮力方法在概念上很简单并且完全正确，但它太慢了。 

关键的观察是每颗恒星都贡献一个分段线性函数。 围绕其首选角度 (a_i)，当恒星做出贡献时，其在朝向 (a_i) 的途中的坡度为 (+s_i)，在经过 (a_i) 后的坡度为 (-s_i)。 一旦其贡献达到零，其斜率就变为零。 

假设

 [
 r_i=\min\left(\pi,\frac{T_i}{s_i}\right)
 ]

 对于（s_i>0）。 该贡献仅在三个相关角度改变其斜率：左端点 (a_i-r_i)、峰值 (a_i) 和右端点 (a_i+r_i)。 在这三个位置，斜率的变化分别为

 [
 +s_i,\qquad -2s_i,\qquad +s_i。 
]

 因此，一颗恒星可以仅由三个斜率变化事件来代表。 这是扫线解决方案使用的中心缩减。 该问题的解决方案正好使用这种三事件表示，并显式处理跨越 (0) 和 (2\pi) 的间隔。 

我们不是重新计算每个候选角度的总和，而是计算角度 (0) 处的总贡献，计算紧邻 (0) 右侧的总函数的导数，然后按排序顺序扫描所有 (O(N)) 事件角度。 

在两个连续的事件角之间，每颗恒星都有固定的线性行为。 因此，总贡献也具有恒定的斜率。 如果当前值为 (E)，当前斜率为 (D)，下一个事件的角度为 (x)，则

 [
 E\leftarrow E+D(x-\text{前一个角度})。 
]

 到达 (x) 后，我们将此处发生的所有斜率变化相加。 这使我们能够仅使用每个事件的恒定功来维持精确的分段线性函数。 

圆形边界需要一个额外的细节。 如果星形的左端点为负，则其间隔穿过（0），因此其（+s_i）斜率变化已经在角度（0）之前发生。 我们将 (s_i) 添加到初始斜率，并通过添加 (2\pi) 来标准化左侧事件。 类似地，如果右端点超过 (2\pi)，则右端点已回绕，因此 (0) 右侧紧邻的斜率已经位于右端点处的 (+s_i) 事件之后。 我们从初始斜率中减去 (s_i)，并通过减去 (2\pi) 来标准化该事件。 

(s_i=0) 的恒星贡献了一个常数 (T_i)，因此它贡献了初始能量，但不产生任何事件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(N^2)) | (O(N)) | 太慢了|
 | 最佳扫描| (O(N\log N)) | (O(N)) | 已接受 |

 ## 算法演练

 1. 读取所有恒星并计算发射角 (0) 处的总贡献。 对于具有首选角度（a_i）的恒星，其距（0）的距离为（\min（a_i，2\pi-a_i）），因此其初始贡献是可以直接计算的。 
2. 如果(s_i=0)，则将(T_i)添加到初始能量并且不创建任何事件。 它的贡献永远不会随着发射角度的变化而改变。 
3. 对于 (s_i>0)，计算有效半径

 [
 r_i=\min\left(\pi,\frac{T_i}{s_i}\right)。 
]

 (\pi) 处的上限是必要的，因为圆角距离永远不会超过 (\pi)。 如果 (T_i/s_i\geq\pi)，则恒星围绕圆永远不会变得不活跃。

1. 为明星创建三个事件。 在 (a_i-r_i) 处，斜率增加 (s_i)。 在 (a_i) 处，斜率减小 (2s_i)。 在 (a_i+r_i) 处，斜率增加 (s_i)。 
2. 将端点归一化到区间 ([0,2\pi]) 上。 如果左端点为负，则将 (s_i) 添加到初始斜率并将 (2\pi) 添加到端点。 如果右端点超过 (2\pi)，则从初始斜率中减去 (s_i)，并从端点中减去 (2\pi)。 这会将循环间隔转换为普通的排序事件，同时保留紧邻角度 (0) 右侧的函数。 
3. 按角度对所有事件进行排序。 最多有 (3N) 个事件，因此成本为 (O(N\log N))。 
4. 以角度 (0)、先前计算的初始能量和初始斜率开始扫描。 对于每个事件角 (x)，首先将能量推进

 [
 \text{当前斜率}\times(x-\text{先前角度})。 
]

 然后将该能量记录为候选最大值并应用事件的斜率变化。 

1. 返回扫描过程中遇到的最大能量。 还考虑角度 (0) 处的初始能量，因为最佳值可以恰好发生在圆形边界处。 

### 为什么它有效

 对于一颗恒星，虽然其贡献为正且发射角向 (a_i) 移动，但贡献以恒定斜率 (+s_i) 变化。 经过(a_i)后，斜率变为(-s_i)。 在贡献达到零的点处，斜率变回零。 因此，每颗恒星都可以通过其初始贡献和三个斜率变化事件来完整表示。 

分段线性函数的和本身是分段线性的。 在两个连续事件之间，其斜率是恒定的，因此可以通过前一个事件的线性插值来精确获得该值。 在斜率发生变化的每个点，扫描都会在继续之前更新该斜率。 

唯一能够产生局部最大值的向下斜率跳跃发生在恒星的首选角度。 截止点产生向上的斜率变化，并且当距离函数环绕对映点时，其斜率也向上变化。 因此，始终可以在事件位置之一找到最大值，特别是在恒星的首选角度或角度 (0) 处。 由于扫描会访问所有这些位置并保持它们之间的精确值，因此它记录的最大值是全局最大值。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

PI = math.pi
TWO_PI = 2.0 * math.pi

def solve():
    n_line = input().strip()
    if not n_line:
        return

    n = int(n_line)

    events = []
    energy = 0.0
    initial_slope = 0.0

    for _ in range(n):
        t, s, a = map(float, input().split())

        # Contribution at angle 0.
        dist0 = min(a, TWO_PI - a)
        energy += max(0.0, t - s * dist0)

        if s == 0.0:
            # Constant contribution, so there are no slope changes.
            continue

        # The circular distance is never larger than pi.
        radius = min(PI, t / s)

        left = a - radius
        right = a + radius

        # The interval may cross angle 0.
        if left < 0.0:
            initial_slope += s
            left += TWO_PI

        # The interval may cross angle 2*pi.
        if right > TWO_PI:
            initial_slope -= s
            right -= TWO_PI

        # Slope changes:
        # left endpoint: 0 -> +s
        # center:        +s -> -s
        # right endpoint: -s -> 0
        events.append((left, s))
        events.append((a, -2.0 * s))
        events.append((right, s))

    events.sort()

    answer = energy
    current_angle = 0.0
    slope = initial_slope

    for angle, delta_slope in events:
        energy += slope * (angle - current_angle)

        if energy > answer:
            answer = energy

        slope += delta_slope
        current_angle = angle

    print(f"{answer:.10f}")

if __name__ == "__main__":
    solve()
```第一部分`solve`计算角度 (0) 处的函数值。 这给出了扫描的起点，并且还涵盖了最佳值恰好位于圆形边界处的情况。 

这`s == 0.0`检查必须在计算之前进行`t / s`。 这样的恒星是恒定的，不需要发生任何事件。 

对于其他每一位明星来说，`radius = min(PI, t / s)`描述了恒星的线性表达式可能起作用的角度范围。 上限 (\pi) 还可以处理在整个循环中贡献保持正值的恒星。 

三个附加事件仅编码导数的变化。 在左端点，导数从零变为 (+s)，因此事件为`s`。 在首选方向上，它从 (+s) 变为 (-s)，总变化为`-2*s`。 在右端点，它从 (-s) 变回零，因此事件再次发生`s`。 

这`initial_slope`调整是实施过程中的微妙部分。 在扫描开始之前，区间交叉点 (0) 已经通过了其左端点，因此最初必须包括其正斜率。 相反，右端点经过 (2\pi) 的区间已经在角度 (0) 之前经过了右端点，因此它的贡献已经在下降，我们从初始导数中减去它的最终 (+s) 斜率变化。 

同一角度的事件不需要特殊分组。 当它们的角度相等时，从一个事件前进到下一个事件的成本为零，因此它们的坡度变化只是一个接一个地应用。 处理等角事件时，函数值不变。 

蟒蛇的`float`是 IEEE-754 双精度数，其精度远高于所需的 (10^{-6}) 输出容差。 最大可能的总贡献最多为 (10^8)，因此也不存在整数溢出问题。

 ## 边缘情况

 对于零斜率，考虑```
1
10 0 2
```贡献始终为 (10)，因此初始能量为 (10)，不会生成任何事件，并且扫描无需处理任何内容。 答案仍然是（10）。 这就是为什么当 (s_i=0) 时必须跳过除以 (s_i) 的原因。 

对于区间交叉角 (0)，请考虑```
2
10 1 0.1
10 1 6.2
```第一个星形的有用区间从 (0.1) 向左延伸到 (-0.9)，而第二个星形的有用区间从 (6.2) 向右延伸超过 (2\pi)。 第一个间隔在角度 (0) 之后立即贡献其正斜率，而第二个间隔已经通过其右端点。 初始斜率调整恰好处理这两个事实，然后按普通递增顺序扫描标准化事件。 

对于影响半径达到 (\pi) 的情况，考虑```
1
3.141593 1 0
```有效半径的上限为 (\pi)。 左端点为 (0-\pi)，归一化为 (\pi)，右端点为 (0+\pi)，也归一化为 (\pi)。 两个端点事件发生在同一位置。 它们组合的斜率变化正确地描述了对映点处圆距离的尖点。 该函数在角度 (0) 处最大，给出 (3.141593)。 

对于同时发生的事件，请考虑```
2
