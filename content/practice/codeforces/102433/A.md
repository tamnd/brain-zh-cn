 ## 解决方案
 ## 问题理解

 城市和道路形成一棵加权树。 每个城市 (i) 都有一个税值 (t_i)，从城市 (u) 到城市 (v) 的机票费用为

 [
 (t_u+t_v)d(u,v),
 ]

 其中 (d(u,v)) 是两个城市之间唯一路径上的总道路通行费。 

如果城市 (u) 获胜，它将向所有其他城市发送一张门票。 我们需要所有 (n-1) 张门票的总成本：

 \sum_{v\ne u}(t_u+t_v)d(u,v)。 
]

 输入给出了城市数量、其税值以及 (n-1) 条加权道路。 输出包含每个可能获胜城市的总计。 

关键约束是 (n\le 100000)。 检查每对城市的解决方案已经太慢了，因为大约有 (10^{10}) 对。 即使是 (O(n^2)) 算法在三秒的时间限制下也是无法实现的。 树结构为我们提供了一种从一个城市移动到邻近城市的方法，同时在恒定时间内更新先前计算的答案。 

这些值也足够大，以至于 32 位整数不安全。 一条路径可以包含几乎 (100000) 个权重 (1000) 的边，距离接近 (10^8)。 乘以税收值并对所有城市求和后，答案可达 (10^{16}) 左右。 Python 整数会自动处理此问题，而 C++ 等语言则需要 64 位整数。 

有几个小案例暴露了推导中的错误。 一个城市根本不需要门票。 为了```
1
7
```输出是```
0
```因为唯一的距离是从城市到它本身，它是零。 假设每个城市都有一个邻居的实现在这里可能会失败。 

拥有两个城市，```
2
2 5
1 2 1000
```距离为 (1000)，因此任一获胜者的成本为

 [
 (2+5)\cdot1000=7000。 
]

 输出是```
7000
7000
```一个常见的错误是只计算涉及获胜者税的部分而忘记了目的地税。 

当树高度不平衡时，会出现不同的问题。 为了```
3
1 2 3
1 2 1
2 3 1
```距离总和为 (3,2,3)，而税收加权距离总和为 (8,4,6)。 因此答案是 (11,8,15)。 递归 DFS 可以在包含（100000）个城市的链上达到 Python 的递归限制，因此实现应该使用迭代遍历。 

## 方法

 直接的解决方案是从每个可能获胜的城市进行树遍历。 一次遍历计算距起始城市的所有距离，然后我们可以对 ((t_u+t_v)d(u,v)) 求和。 遍历一棵树需要 (O(n))，而从所有 (n) 个城市进行遍历则需要 (O(n^2))。 在最坏的情况下，这意味着处理 (n(n-1)) 条边的定向树遍历，即 (100000\cdot99999=9,999,900,000) 条边访问。 这远远超出了可用时间。 

有用的观察是总成本可以分为两个独立的距离总和：

 [
 \开始{对齐}
 \text{答案}_u
 &=\sum_v(t_u+t_v)d(u,v)\
 &=t_u\sum_v d(u,v)+\sum_vt_vd(u,v)。 
\结束{对齐}
 ]

 定义

 [
 A_u=\sum_v d(u,v)
 ]

 和

 [
 B_u=\sum_v t_vd(u,v)。 
]

 然后

 [
 \text{answer}_u=t_uA_u+B_u。 
]

 所以我们只需要每个 (A_u) 和每个 (B_u)。 

现在将树植根于城市 (1)。 假设 (v) 是 (u) 的子级，由权重 (w) 的边连接，并且 (v) 的子树包含 (s) 个城市。 当我们从 (u) 移动到 (v) 时，(v) 子树内的每个城市都变得 (w) 更近，而其外部的每个城市都变得 (w) 更远。 因此

 [
 A_v=A_u+w((n-s)-s)
 =A_u+w(n-2s)。 
]

 同样的推理也适用于税收加权总和。 令 (S) 为整棵树的总税收，(S_v) 为 (v) 子树内的总税收。 子树内部的税收加权距离减少 (wS_v)，而外部的税收加权距离增加 (w(S-S_v))。 因此

 # B_u+w((S-S_v)-S_v)

 B_u+w(S-2S_v)。 
]

 这是树重新生根的中心步骤。 一旦子树大小和子树税额已知，将答案移动到一条边上需要恒定的时间。 

从根开始遍历一次即可得到初始值(A_1)和(B_1)。 在遍历过程中，从根到每个城市的距离是已知的，因此我们累加两个总和。 然后反向遍历计算子树大小和税金。 最后，向前遍历应用两个重根公式。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(n^2)) | (O(n)) | (O(n)) | 太慢了|
 | 最佳 | (O(n)) | (O(n)) | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1. 以城市 (1) 为树根并执行迭代 DFS 或堆栈遍历。 存储每个城市的父级、其父级边的权重以及距根的距离。 同时记录遍历顺序。 

该顺序为我们提供了一种方便的方法，可以稍后将树从叶子返回到根，而无需递归。 
2. 在发现每个城市（v）的同时，将其根距离累加为

 [
 A_1=\sum_v d(1,v)
 ]

 及其税收加权距离

 [
 B_1=\sum_v t_vd(1,v)。 
]

 到根的距离已经可用，因此不需要额外的遍历。 
3. 将每个子树大小初始化为 (1)，并将每个子树税额初始化为城市自己的税额。 逆向处理记录的顺序。 对于每个非根城市 (v)，将其子树大小和子树税额添加到其父级。 

经过这一关后，`size[v]`是 (v) 以下的城市数量，包括 (v)，以及`sub_tax[v]`是其税值的总和。 这些正是重生公式所需的数量。 
4. 将根的距离和和加权距离和设置为步骤 2 中计算的值。其最终答案是

 [
 t_1A_1+B_1。 
]
 5. 按照原始的根到叶顺序处理城市。 对于每个非根城市 (v)，令 (p) 为其父城市，(w) 为边权重。 使用更新普通距离和

 [
 A_v=A_p+w(n-2,\text{大小}[v])。 
]

 项 (n-2,\text{size}[v]) 计算从 (p) 到 (v) 跨越边缘时有多少城市移动得更远减去有多少城市移动得更近。 
6. 使用更新加权距离和

 [
 B_v=B_p+w(S-2,\text{sub_tax}[v]),
 ]

 其中（S）是每个城市的税收总额。 

同样的重新定位论点也适用，只不过每个城市缴纳其税收而不是单位缴款。 
7. 计算

 [
 \text{answer}_v=t_vA_v+B_v
 ]

 每个城市并打印结果。 

### 为什么它有效

 对于每个城市 (u)，所需成本恰好是 (t_uA_u+B_u)，因此计算这两个量就足够了。 根处的初始值直接从所有根距离获得。 考虑任何父子边 (u)-(v)。 (v) 子树中的每个城市将其距离更改为 (-w)，该子树之外的每个城市的距离更改为 (+w)。 这给出了 (A_v) 的公式。 如果每个城市都按其税收进行加权，则同一分区给出 (B_v) 的公式。 由于子树大小和税额是精确的，因此每个重新定位步骤都会根据其父级的精确值生成子级的精确值。 因此，从正确的根值开始，访问从父级到子级的每一条边，计算出每个城市的正确值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    tax = list(map(int, input().split()))

    graph = [[] for _ in range(n)]

    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append((v, w))
        graph[v].append((u, w))

    parent = [-1] * n
    parent[0] = 0
    parent_weight = [0] * n
    dist = [0] * n
    order = []

    stack = [0]

    root_dist_sum = 0
    root_weighted_dist_sum = 0

    while stack:
        u = stack.pop()
        order.append(u)

        root_dist_sum += dist[u]
        root_weighted_dist_sum += tax[u] * dist[u]

        for v, w in graph[u]:
            if v == parent[u]:
                continue

            parent[v] = u
            parent_weight[v] = w
            dist[v] = dist[u] + w
            stack.append(v)

    size = [1] * n
    sub_tax = tax[:]

    for u in reversed(order[1:]):
        p = parent[u]
        size[p] += size[u]
        sub_tax[p] += sub_tax[u]

    total_tax = sub_tax[0]

    distance_sum = [0] * n
    weighted_distance_sum = [0] * n
    answer = [0] * n

    distance_sum[0] = root_dist_sum
    weighted_distance_sum[0] = root_weighted_dist_sum
    answer[0] = tax[0] * distance_sum[0] + weighted_distance_sum[0]

    for v in order[1:]:
        p = parent[v]
        w = parent_weight[v]

        distance_sum[v] = (
            distance_sum[p] + w * (n - 2 * size[v])
        )

        weighted_distance_sum[v] = (
            weighted_distance_sum[p]
            + w * (total_tax - 2 * sub_tax[v])
        )

        answer[v] = (
            tax[v] * distance_sum[v]
            + weighted_distance_sum[v]
        )

    sys.stdout.write("\n".join(map(str, answer)))

if __name__ == "__main__":
    solve()
```邻接表存储了每条路的两个方向，因为初始遍历需要穿过无向树。 这`parent`数组可防止遍历立即越过刚刚使用的边缘走回。 

第一次遍历构建`order`，计算每个根距离，并累加两个根和。 它是迭代的而不是递归的，因为一棵树可以是（100000）个城市的单个链。 

反向传递计算`size`和`sub_tax`。 在父母之前处理孩子才是使积累正确的原因。 根的值是已知的，因此最终的前向传递可以在计算出其父级的值后处理每个子级。 

表达式`n - 2 * size[v]`和`total_tax - 2 * sub_tax[v]`是有符号值。 当子子树包含一半以上的城市或一半以上的总税收时，它们可能为负数。 代码不得用绝对值替换它们。 

根的父级设置为其自身，这可以防止在初始遍历期间重新访问它。 与根相关联的边权重是不相关的并且被初始化为零。 

没有特殊的循环或除法，Python 的任意精度整数可以安全地处理潜在的 (10^{16}) 规模的答案。 在 C++ 中，所有距离和和答案都应使用`long long`。
