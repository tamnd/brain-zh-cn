 ## 解决方案
 ## 问题理解

 问题中有两种可变状态，将它们分开是整个解决方案的关键。 

缓存有`n`字节位置并完全从零开始。 分别有`m`源数组。 加载操作将一个完整的源数组复制到缓存的连续部分。 一旦复制，这些缓存字节就独立于源数组。 稍后对源的更改仅影响未来的负载。 

源更新将一个源数组的连续部分以 256 为模进行递增。打印操作请求一个高速缓存地址处的当前字节。 每个打印操作的输出都是一个字节值。 官方声明给出`n, m, q <= 5 * 10^5`，而所有源数组的总长度也最多为`5 * 10^5`; 时间限制为5秒。 

大的`q`立即排除每次加载时执行与加载数组的长度成比例的工作。 单个源数组可能有长度`5 * 10^5`并且可以被加载数十万次，所以`O(s_i)`负载操作可能会导致大约`2.5 * 10^11`字节分配。 有界的总源数组大小对此没有帮助，因为可以重复加载相同的源。 

还有一个时间问题使得直接模拟非常容易出错。 假设源包含`[10, 20]`，我们加载它，然后将源增加到`[11, 21]`。 缓存必须仍然包含`[10, 20]`。 一种保留对源的引用并在打印时对其进行评估的解决方案会错误地生成新值。 

另一个边缘情况是重叠负载。 考虑：```
3 1 3
2 5 6
1 1 1
1 1 2
2 2
```第一个负载放置`[5, 6]`在位置 1 和 2。第二个负载放置`[5, 6]`在位置 2 和 3。最终答案是`5`，因为位置 2 被第二次加载覆盖。 仅记住覆盖每个位置的第一个负载的解决方案将返回错误的快照。 

卸载的缓存位置也必须保持为零。 例如：```
2 1 2
1 7
2 2
2 1
```输出是：```
0
0
```这两个位置都没有被加载过。 假设每个打印都对应于某个源数组的解决方案将发明一个不存在的值。 

最后，增量可以围绕 256 进行回绕，并且回绕对于每个字节独立发生。 例如：```
1 1 4
1 255
3 1 1 1
1 1 1
2 1
```输出是`0`。 第一次加载与最终查询无关。 第二次加载发生在增量之后，所以它看到`255 + 1 = 0`。 保留普通整数和而不在适当的点减少模 256 最终会产生不正确的字节。 

## 方法

 直接的方法是显式地表示缓存。 源负载`i`在位置`p`全部复制`s_i`字节，源更新循环`l`通过`r`，并且打印读取一个缓存单元。 这是正确的，因为它完全遵循操作。 

问题是加载操作。 如果源有长度`5 * 10^5`，一次加载已经花费了 50 万个任务。 和`5 * 10^5`这样的负载，最坏的情况达到`2.5 * 10^11`作业。 对于如此大量的工作来说，五秒是远远不够的。 

第一个有用的观察是打印查询不需要整个缓存。 它只需要知道**覆盖该地址的最新负载**。 一旦我们知道该负载，缓存值就恰好是该负载时拍摄的源快照的一个字节。 

这将缓存问题变成了范围分配问题，其中唯一的查询是点查询。 对于这种情况，有一个特别简单的线段树表示。 当负载覆盖一个区间时，将该区间分解为通常的规范线段树节点，并将负载的操作编号放入每个这样的节点中。 对于缓存位置，从其叶子走到根并获取遇到的最大操作数。 该最大值正是覆盖该位置的最新负载。 

第二个观察结果是关于源快照的。 假设在缓存位置打印`p`指操作时的负载`t`。 如果该负载启动源`i`在缓存位置`start`，那么打印的字节就是源位置`p - start + 1`正如消息来源所看到的操作`t`。 

我们可以发现这些`(load time, source offset)`第一次通过期间的请求。 然后我们按时间顺序进行第二次操作。 当我们到达负载时间时`t`，该负载之前的所有源更新均已应用，因此源完全处于负载复制时的状态。 我们可以回答涉及当时负载的每个打印查询。 

对于源更新，源数组可以串联成一个概念数组，因为更新永远不会从一个源跨越到另一个源。 支持范围添加和点查询的线段树可以维护所有源增量。 它不需要每个节点上的延迟传播或完整值。 每个范围添加都存储在其规范线段树节点上，并且点查询对到叶子的路径上的标签进行求和。 

因此，这两个遍解决了两个独立的问题。 第一个线段树回答“哪个负载拥有这个缓存位置？” 第二个线段树回答“当负载发生时，这个源位置的值是多少？”

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(q * max(s_i) + q * max(s_i))`在最坏的情况下|`O(n + sum s_i)`| 太慢了|
 | 最佳 |`O((q + sum s_i) log(max(n, sum s_i)))`|`O(n + q + sum s_i)`| 已接受 |

 蛮力界限可以更具体地视为最多`2.5 * 10^11`仅从加载中缓存分配。 最佳方法每次加载、打印和源更新仅执行对数工作。 

## 算法演练

 1. 将所有源数组连接成一个字节数组。 记录每个源的起始全局位置。 由于总源长度最多为`5 * 10^5`, this uses linear space.
 2. 在缓存地址上构建段树。 最初，每个树标记都为零，这意味着没有负载覆盖缓存的该部分。 
3. 按时间顺序处理第一遍中的操作。 对于运行时的负载`t`，确定其缓存间隔并写入`t`进入覆盖该区间的规范线段树节点。 我们不会向下传播这些值，因为稍后的点查询可以简单地检查其叶子的每个祖先。 
4. 对于缓存位置的打印`p`，从其叶子走到根并找到该路径上最大的负载操作数。 如果最大值为零，则缓存位置从未被加载过，因此答案为零。 
5. 如果打印属于运行时负载`t`，解码该负载的源和起始缓存位置。 对应的源偏移量为`p - start + 1`。 将此偏移量存储在附加到操作的请求列表中`t`。 输出槽也会被记录，因此稍后可以响应请求，而无需更改其原始输出顺序。 
6. 在执行第一遍时紧凑地存储操作。 第二遍只需要加载和源更新操作，因此实现将每个操作打包为 64 位整数，而不是保留大型 Python 元组。 
7. 清除线段树并将其重新用于源数组。 从概念上将源连接到一个坐标系中。 源上的源更新`i`, 职位`l`通过`r`，成为全局区间的范围加法`[base[i] + l - 1, base[i] + r - 1]`。 
8. 按时间顺序重播操作。 对于源更新，请向该全局范围添加一个。 对于运行时的负载`t`，之前发生的所有源更新`t`现已应用。 遍历附上的请求列表`t`，并且对于每个请求的源偏移量，读取其原始字节加上该位置处的累积增量，减少模 256。 
9. 回放结束后，每条打印结果均按原来的顺序填写。 将答案的字节数组写入作为最终输出。 

### 为什么它有效

 对于每个缓存位置，第一段树都保持不变式，即其根到叶路径上的最大负载时间戳是其间隔包含该位置的最新负载。 因此，每个打印都与当前存在字节的负载相关联。 

对于与负载相关的请求`t`，第二遍到达运行`t`仅在处理之前的每个源更新之后`t`并在处理之后的任何内容之前`t`。 因此，此时读取的源值正是负载复制的值。 稍后的源更新无法更改已加载的缓存字节，因此在加载时间戳处应答请求相当于在原始打印操作处应答请求。 

这两个不变量一起给出每个打印查询的精确缓存值。 

## Python 解决方案```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    input = sys.stdin.readline

    n, m, q = map(int, input().split())

    # base[i] is the 1-based global position of the first byte of source i.
    base = [0] * (m + 2)
    data = bytearray()

    pos = 1
    for i in range(1, m + 1):
        parts = input().split()
        s = int(parts[0])
        base[i] = pos
        data.extend(int(x) for x in parts[1:])
        pos += s

    total = pos - 1
    base[m + 1] = pos

    # One tree size is enough for both the cache and the concatenated sources.
    limit = max(n, total)
    size = 1
    while size < limit:
        size <<= 1

    # First pass: tree[node] stores the latest load timestamp covering
    # the interval represented by this node.
    tree = [0] * (2 * size)

    # Operations are packed into 64-bit integers.
    # Bits 60..61: type
    # Bits 40..59: first argument
    # Bits 20..39: second argument
    # Bits 0..19 : third argument
    ops = array('Q', [0]) * (q + 1)

    # Requests belonging to load time t form a linked list.
    head = array('i', [-1]) * (q + 1)
    req_offset = array('i')
    req_next = array('i')

    # One byte per print query, in original query order.
    answers = bytearray()

    MASK = (1 << 20) - 1

    for t in range(1, q + 1):
        parts = input().split()
        typ = int(parts[0])

        if typ == 1:
            src = int(parts[1])
            start = int(parts[2])

            ops[t] = (1 << 60) | (src << 40) | start

            if src < m:
                length = base[src + 1] - base[src]
            else:
                length = total - base[src] + 1

            left = size + start - 1
            right = size + start + length - 1  # exclusive

            # Range assignment of timestamp t.
            while left < right:
                if left & 1:
                    tree[left] = t
                    left += 1
                if right & 1:
                    right -= 1
                    tree[right] = t
                left >>= 1
                right >>= 1

        elif typ == 2:
            p = int(parts[1])

            node = size + p - 1
            load_time = 0

            while node:
                value = tree[node]
                if value > load_time:
                    load_time = value
                node >>= 1

            query_id = len(answers)
            answers.append(0)

            if load_time != 0:
                load_code = ops[load_time]
                src = (load_code >> 40) & MASK
                start = load_code & MASK

                offset = p - start + 1

                req_offset.append(offset)
                req_next.append(head[load_time])
                head[load_time] = query_id

        else:
            src = int(parts[1])
            left_pos = int(parts[2])
            right_pos = int(parts[3])

            ops[t] = (
                (3 << 60)
                | (src << 40)
                | (left_pos << 20)
                | right_pos
            )

    # Reuse the tree for range-add / point-query operations on source data.
    tree = [0] * (2 * size)

    for t in range(1, q + 1):
        code = ops[t]
        if code == 0:
            continue

        typ = code >> 60

        if typ == 3:
            src = (code >> 40) & MASK
            left_pos = (code >> 20) & MASK
            right_pos = code & MASK

            left = size + base[src] + left_pos - 2
            right = size + base[src] + right_pos - 1  # exclusive

            while left < right:
                if left & 1:
                    tree[left] += 1
                    left += 1
                if right & 1:
                    right -= 1
                    tree[right] += 1
                left >>= 1
                right >>= 1

        elif typ == 1:
            load_code = code
            src = (load_code >> 40) & MASK

            request = head[t]
            if request == -1:
                continue

            source_base = base[src]

            while request != -1:
                offset = req_offset[request]
                global_pos = source_base + offset - 1

                node = size + global_pos - 1
                added = 0

                while node:
                    added += tree[node]
                    node >>= 1

                answers[request] = (data[global_pos - 1] + added) & 255
                request = req_next[request]

    return ''.join(chr(x + 48) if x < 10 else str(x) + '\n'
                   for x in answers)

if __name__ == "__main__":
    sys.stdout.write(solve())
```仅在第二阶段将源阵列展平。`base[i]`给出源的第一个全局位置`i`，所以源位置`k`对应于`base[i] + k - 1`。 

第一个线段树故意不是普通的惰性传播树。 它的条目是时间戳，而不是实际的缓存字节。 范围加载将其时间戳写入`O(log n)`规范节点。 点查询检查所有祖先并获取它们的最大值。 由于时间戳随着操作的处理而增加，因此最大的时间戳正是最近的覆盖负载。 

操作编号与操作参数打包在一起。 所有相关坐标如下`5 * 10^5`，因此每个坐标 20 位就足够了。 这可以避免存储数十万个 Python 元组，这会消耗更多的内存。 

请求列表也使用整数数组存储。 请求由其输出位置标识，并且`head[t]`指向依赖于负载的所有打印查询`t`。 这使得第二遍在达到相应的负载后立即回答整组查询。 

第二棵树仅存储范围添加。 范围增量被分解为规范节点并将其标签加一。 点查询对其根到叶路径上的标签求和。 该总和是影响字节的源增量的数量。 

表达式`(original + added) & 255`等价于模 256，因为两个值都是非负数，并且 256 是 2 的幂。 它还保持操作紧凑。 

问题中的所有区间都是基于 1 的且包含在内。 迭代线段树表示在内部使用半开区间，这就是为什么右端点被转换为独占坐标的原因。 源偏移量也是明确的`p - start + 1`，这避免了将缓存地址转换回源索引时常见的单位置错误。 

## 工作示例

 ### 示例 1

 官方样本有两个来源，`[255, 0, 15]`和`[1, 2, 1, 3]`，具有重叠负载和稍后的源更新。 它的输出是`0, 255, 1, 255, 0, 3`。 

| 运营| 首过状态 | 请求已创建 | 第二遍值 |
 | --- | --- | --- | --- |
 |`2 1`| 位置 1 无负载 | 无 |`0`|
 |`1 2 2`| 位置 2..5 获得负载`2`| 无 | 来源 2 快照 |
 |`1 1 1`| 位置 1 获得负载`3`| 无 | 来源 1 快照 |
 |`2 1`| 最新负载是`3`， 抵消`1`|`(3, 1)`|`255`|
 |`2 4`| 最新负载是`2`， 抵消`3`|`(2, 3)`|`1`|
 |`3 1 1 2`| 缓存标签不变| 无 | 仅源 1 发生变化 |
 |`2 1`| 最新负载仍然`3`|`(3, 1)`|`255`|
 |`1 1 2`| 位置 2..4 获取负载`8`| 无 | 来源 1 快照 |
 |`2 2`| 最新负载是`8`， 抵消`1`|`(8, 1)`|`0`|
 |`2 5`| 最新负载是`2`， 抵消`4`|`(2, 4)`|`3`|

 重要的行是操作 7。源 1 已经递增，但在该递增之前缓存位置已被加载 3 填充。 因此，该请求仍然要求源 1 在时间 3 的字节，即`255`。 

在操作 8 中，源 1 具有值`[0, 1, 15]`，因此稍后在位置 2 处加载会复制该较新版本。 该负载后的第二次打印因此观察到`0`而不是旧值`255`。

 考虑这个较小的输入：```

 | 运营| 查询位置处的首次加载 | 请求 | 负载发生时的源状态 | 回答 |
 | --- | --- | --- | --- | --- |
 |`2 1`| 无 | 无 |`[5,6,7]`|`0`|
 |`1 1 2`| 加载`2`涵盖位置 2..4 | 无 |`[5,6,7]`| |
 |`3 1 2 3`| 不变| 无 | 源变成`[5,7,8]`| |

 |`1 1 1`| 新负载涵盖位置 1..3 | 无 |`[5,7,8]`| |

 源更新后的第一个查询仍然返回`6`， 不是`7`，因为它的加载发生在更新之前。 稍后的加载会看到更新并产生`7`。 这正是两遍算法捕获的时间间隔。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O((q + S) log(max(n, S)))`| 每个加载和打印都使用对数缓存树操作，而每个源更新和相关请求都使用对数源树操作。 这里`S = sum s_i <= 5 * 10^5`。 |
 | 空间|`O(n + q + S)`| 两个线段树使用`O(max(n,S))`空间，而源数据、打包操作和请求列表使用线性空间。 |

 和`n`,`q`， 和`S`全部受`5 * 10^5`，对数因子最多约为 19。该实现还使用紧凑整数数组来存储操作日志和请求列表，而源字节各占一个字节。 这使内存与输入大小成正比，而不是与所有加载复制的字节总数成正比。

"""

assert run(modulo_case) == """\
0
0
""", "modulo 256"

# Maximum-size stress case:
# n = 500000, q = 500000, sum(s_i) = 500000.
# Every cache query asks for the final address after one full-length load.
big_data = " ".join(["255"] * 500000)
big_case = (
    "500000 1 500000\n"
    + big_data
    + "\n1 1 1\n"
    + ("2 500000\n" * 499999)
)

assert run(big_case) == "255\n" * 499999, "maximum-size case"

 | --- | --- | --- |

 ## 边缘情况

 ### 缓存位置从未被加载过

 对于```
2 1 2
1 7
2 2
2 1
```第一遍根本不执行范围分配。 两个打印查询都遍历其从根到叶的路径并发现时间戳为零。 他们的答案槽保持为零，产生`0`和`0`。 

对于这种情况，该算法不需要特殊的缓存阵列。 时间戳零自然代表初始全零缓存。 

### 稍后的源更新不得更改旧的缓存副本

 考虑：```
1 1 6
1 42
2 1
3 1 1 1
1 1 1
2 1
3 1 1 1
2 1
```操作 4 处的加载发生在一个源增量之后，因此复制到缓存中的源值是`43`。 操作 6 中的后续增量将源更改为`44`，但缓存仍然存在`43`。 

第一遍将最终打印与负载 4 相关联。在第二遍期间，在应用操作 6 之前，到达操作 4 时会回答该请求。 结果是`43`。 

### 重叠加载必须选择最新的时间戳

 对于：```
5 2 8
2 10 10
3 7 8 9
1 1 1
1 2 2
2 2
3 2 1 3
2 4
1 2 3
2 3
2 5
```第一个负载覆盖位置 1 和 2，而第二个负载覆盖位置 2 到 4。因此，位置 2 处的打印会看到负载 2，而不是负载 1。 

在缓存段树中，负载1将时间戳1写入其间隔的规范节点。 负载 2 随后将时间戳 2 写入其间隔的规范节点。 位置 2 处的查询会看到沿其根到叶路径的两个时间戳，并取最大值，即 2。 

### 负载必须在以后更新之前捕获源

 采取：```
4 1 7
3 5 6 7
2 1
1 1 2
3 1 2 3
2 3
1 1 1
2 2
2 4
```操作 2 时的负载捕获`[5,6,7]`。 操作 3 处的更新将源更改为`[5,7,8]`，但操作 4 处的打印与加载 2 相关联，因此返回`6`。 

当第二遍到达操作 2 时，尚未处理任何源更新。 请求源偏移2读取原始值`6`。 稍后的更新仅在之后处理，因此不会影响该请求。 

### 稍后的加载会看到之前的所有源更新

 在同一示例中，操作 5 在操作 3 更新后加载源。此时源为`[5,7,8]`，因此位置 2 处的打印返回`7`。 

第二遍在到达操作 5 之前已经应用了操作 3。因此附加到负载 5 的请求读取更新的源状态。 因此，同一个源可以在缓存中拥有多个独立的快照。 

### 必须对结果字节应用模 256

 对于：```
3 1 10
2 250 250
1 1 1
3 1 1 2
3 1 1 2
3 1 1 2
3 1 1 2
3 1 1 2
3 1 1 2
1 1 1
2 1
2 2
```每旋转六个增量`250`进入`0`因为`250 + 6 = 256`。 因此第二个负载复制`[0,0]`，并且两个打印都返回零。 

源线段树将增量数存储为普通整数。 这是安全的，因为总和最多为`q`，它很容易适合 Python 的整数。 当重建实际字节值时应用模运算。 

### 加载正好在缓存边界处结束

 在最大尺寸测试中，源 1 具有长度`500000`，以及操作`1 1 1`将其加载到缓存位置`1`通过`500000`。 打印位置`500000`必须映射到源偏移量`500000`。 

范围转换使用独占右端点，因此内部区间为`[1, 500001)`。 点查询使用`size + p - 1`，映射缓存位置`500000`准确地说是它的叶子。 不包含额外的缓存位置，并且最终字节被正确处理。
