 ## 解决方案
 ## 问题理解

 每个脉冲沿着一根导线水平或垂直传播。 电线上的水平脉冲`a`从时间的左边缘开始`t`，而线上的垂直脉冲`a`在相同类型的参考时间从底部边缘开始。 两者都以一速度移动，每个脉冲都有持续时间`m`。 

考虑一个水平脉冲和一个垂直脉冲。 它们正好在一个像素处相交，该像素由它们的两条线号确定。 唯一的问题是两个脉冲是否同时出现在该像素上。 

对于电线上的水平脉冲`a`，其前沿到达垂直线上的像素`b`在某个时间`t + b`。 它的后沿在同一时间到达相同的像素`t + b + m`。 对于导线上的垂直脉冲`b`，对应的区间为`[t_v + a, t_v + a + m_v)`。 半开解释很有用，因为该声明明确表示在某一时刻触摸不会激活像素。 

有一种更简洁的方式来表达这些间隔。 对于水平脉冲，从其起始时间减去其水平线数并定义`start = t - a`。 

对于垂直脉冲，对其垂直线号执行相同的操作。 在此变换之后，两个脉冲在变换后的时间间隔与正长度重叠时恰好发生碰撞。 一个脉冲`(t, m, a)`变成间隔`[t - a, t - a + m)`。 

因此脉冲的二维运动变成了一维间隔重叠问题。 官方竞赛分析描述了将两个脉冲路径投影到对角线上相同的几何思想`x = y`，两个脉冲串以相同的速度移动。 

只有水平和垂直脉冲才能同时激活像素。 两个水平脉冲永远不会在一个像素处相遇，因为它们在不同的行上传播，并且两个垂直脉冲具有类似的属性。 所以答案就是由一个水平间隔和一个垂直间隔组成的重叠对的数量。 

脉冲数最多为`200000`。 每个水平脉冲和每个垂直脉冲之间的直接比较可能需要大约`100000 * 100000 = 10^10`比较，这远远超出了两秒竞赛程序所能达到的效果。 线数最多为`100000`，但构建这种尺寸的网格并不能解决真正的问题，因为重要的维度是脉冲对的数量，而不是电线的数量。 起始时间和长度也足够大，任何依赖于逐个时间单位进行模拟的解决方案都是不合适的。 

有几种边界情况很容易处理不当。 

考虑两个仅接触的脉冲：```
2
h 1 1 1
v 2 1 1
```水平间隔为`[0, 1)`垂直间隔为`[1, 2)`。 答案是`0`。 粗心的实现使用`start <= other_end`或处理闭合间隔会计算此碰撞，即使脉冲永远不会同时存在。 

考虑相同的起始位置：```
2
h 1 3 1
v 1 3 1
```两个变换后的区间都是`[0, 3)`，所以答案是`1`。 相同的起点允许立即重叠。 

一个脉冲也可以完全包含另一个脉冲：```
2
h 1 10 1
v 3 2 1
```间隔是`[0, 10)`和`[2, 4)`，所以答案是`1`。 仅检查一个间隔是否在另一个间隔内开始会错过一些有效的冲突。 

最后，不得对沿同一方向行进的脉冲进行计数：```
2
h 1 10 1
h 5 10 2
```没有垂直脉冲，所以答案是`0`，即使它们的变换间隔重叠。 

## 方法

 暴力解决方案直接来自物理解释。 存储所有水平脉冲和所有垂直脉冲，然后检查每个水平-垂直对。 对于一对，计算其交点处的两个到达间隔并测试它们是否与正长度重叠。 这是正确的，因为每个激活的像素恰好对应于一个水平脉冲和一个垂直脉冲，并且每一对这样的脉冲恰好具有一个交叉像素。 

问题是对的数量。 如果有`100000`水平脉冲和`100000`垂直脉冲，该算法执行`10^10`配对检查。 即使每次比较的常数非常小，也不足以满足两秒的限制。 

有用的观察结果是，在正确的变换后，精确的线坐标消失了。 具有起始时间的水平脉冲`t`， 长度`m`，和行`a`到达对角投影，间隔开始于`t - a`。 具有起始时间的垂直脉冲`t`， 长度`m`，和列`a`得到完全相同的表示。 因此，每个脉冲都成为一条线上的一个普通间隔。 

现在的任务是：给定水平间隔和垂直间隔，计算有多少对与正长度重叠。 

对于一个水平间隔`[L, R)`, 垂直间隔`[S, E)`恰好重叠它的时候`S < R`和`E > L`。 

我们可以通过对所有垂直起始点进行排序并使用二分搜索来计算第一个条件。 我们可以通过对所有垂直端进行排序并使用另一个二分搜索来计算第二个条件。 满足这两个条件的数为`number of vertical starts < R - number of vertical ends <= L`。 

这避免了任何二维数据结构。 在垂直端点排序后，通过两次二分搜索来处理每个水平间隔。 相反，官方社论描述了对四种间隔事件的等效扫描，保持有多少水平和垂直间隔处于活动状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取每个脉冲并将其转换为一维区间。 如果脉冲有起始时间`t`, 线号`a`，和长度`m`, 计算`L = t - a`和`R = L + m`。 店铺`[L, R)`根据其方向在水平或垂直集合中。 减法为`a`考虑了到达交叉点像素所需的额外行程时间。 
2. 分离所有垂直间隔的端点。 将每个垂直起点存储在一个数组中，将每个垂直终点存储在另一个数组中。 对两个数组进行排序。 我们只需要垂直间隔来进行查询，因为每次有效碰撞都恰好有一个水平脉冲和一个垂直脉冲。 
3. 对于每个水平间隔`[L, R)`，找出之前开始的垂直间隔有多少个`R`。 使用已排序的起始数组，`bisect_left(starts, R)`准确地给出了这个计数。 严格的不等式是有意为之的，因为间隔正好从`R`只触及水平间隔的端点。 
4. 找出有多少个垂直间隔在 或之前结束`L`。 使用已排序的结束数组，`bisect_right(ends, L)`给出这个计数。 这样的间隔不能重叠`[L, R)`，因为它们的电流已经随着时间消失了`L`。 
5. 从第一个计数中减去第二个计数。 每个剩余的垂直间隔都满足`S < R`和`E > L`，因此它与水平间隔重叠一段正时间。 将此数字添加到答案中。 
6. 打印累计答案。 Python 整数是无界的，这很有用，因为多达`100000 * 100000 = 10^10`像素可以被激活。 

### 为什么它有效

 对于每个水平和垂直脉冲对，变换后的间隔准确地保留了它们的电流是否共存于相应的像素处。 两个变换的区间`[L, R)`和`[S, E)`精确重叠时`S < R`和`E > L`。 对于每个水平间隔，第一次二分查找计算所有满足的垂直间隔`S < R`，而第二个则完全删除那些`E <= L`。 每个剩余的垂直间隔都与水平间隔重叠，并且每个重叠的垂直间隔都保留在计数中。 由于每一水平-垂直对对应一个像素，因此累积计数恰好是激活像素的数量。 

## Python 解决方案```python
import sys
from bisect import bisect_left, bisect_right

input = sys.stdin.readline

def solve(reader=None):
    if reader is None:
        reader = sys.stdin.readline

    n = int(reader())

    horizontal = []
    vertical_starts = []
    vertical_ends = []

    for _ in range(n):
        direction, t, m, a = reader().split()
        t = int(t)
        m = int(m)
        a = int(a)

        left = t - a
        right = left + m

        if direction == 'h':
            horizontal.append((left, right))
        else:
            vertical_starts.append(left)
            vertical_ends.append(right)

    vertical_starts.sort()
    vertical_ends.sort()

    answer = 0

    for left, right in horizontal:
        starts_before_right = bisect_left(vertical_starts, right)
        ends_at_or_before_left = bisect_right(vertical_ends, left)
        answer += starts_before_right - ends_at_or_before_left

    return answer

if __name__ == "__main__":
    print(solve())
```输入循环立即执行几何变换，因此之后不需要原始线号。 对于一个脉冲`(t, m, a)`,`left = t - a`和`right = left + m`描述投影线上的间隔。 

仅垂直端点需要排序。 对于每个水平间隔，`bisect_left(vertical_starts, right)`计数严格在正确端点之前开始。 使用`bisect_left`而不是`bisect_right`是排除仅接触的间隔`right`。 

对于另一个边界，`bisect_right(vertical_ends, left)`计数小于或等于左端点的端点。 使用`bisect_right`是什么删除了恰好结束的时间间隔`left`，符合端点接触不激活像素的声明规则。 

答案可以达到`10^10`，因此在整数具有固定宽度的语言中，32 位整数是不够的。 Python 的整数类型直接处理它。

 ## 边缘情况

 端点接触的情况由严格的二分搜索边界处理。 为了```
2
h 1 1 1
v 2 1 1
```水平脉冲变为`[0, 1)`垂直脉冲变为`[1, 2)`。`bisect_left(starts, 1)`不计算垂直起点`1`，所以答案是`0`。 这直接编码了同时存在必须持续一定时间的规则。 

对于相同的起始位置，```
2
h 1 3 1
v 1 3 1
```两个间隔都是`[0, 3)`。 垂直开始`0`严格位于水平右端点之前`3`，和垂直端`3`严格位于水平左端点之后`0`。 计算该对，给出`1`。 

为了遏制，```
2
h 1 10 1
v 3 2 1
```间隔是`[0, 10)`和`[2, 4)`。 垂直启动满足`2 < 10`，其终点满足`4 > 0`，因此它贡献了一次碰撞。 该方法不假设任一间隔必须包含另一个间隔的端点。 

对于同向脉冲，```
2
h 1 10 1
h 5 10 2
```水平间隔集合包含两个脉冲，而垂直端点数组为空。 每个水平查询贡献为零，所以答案是`0`。 这可以防止同一方向的重叠投影间隔被误认为是物理像素激活。 

对于最大尺寸的情况，有`100000`水平和`100000`垂直脉冲，每个都转换成`[100000, 300000)`。 每个水平间隔与每个垂直间隔重叠，产生`10^10`激活的像素。 该算法从不单独枚举这些对。 它通过每个水平间隔进行两次二分搜索来对它们进行计数，这正是 O(n log n) 方法仍然实用的原因。
