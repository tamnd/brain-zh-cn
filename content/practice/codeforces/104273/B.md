 ## 解决方案
 ## 问题理解

 两个自动机器人按照严格的时间表互相发送消息。 两个机器人始终在时间 0 发送消息，然后继续定期发送消息：第一个机器人在时间 0、a、2a、3a 等发送，而第二个机器人在时间 0、b、2b、3b 等发送。 系统仅运行固定的持续时间 T，并且任何恰好在时间 T 安排的消息仍然被计数。 

任务是确定每个机器人在时间 0 到时间 T（含）的时间间隔内发送了多少条消息。 

直接的解释是，对于每个机器人，我们正在计算其周期的多少倍位于 [0, T] 范围内。 这将问题变成了算术级数的计数问题。 

这些约束允许 a、b 和 T 的值最多为 10^9。这会立即排除随着时间的推移进行任何模拟，因为每秒逐步达到 T 需要最多 10^9 次迭代，这远远超出了 1 秒的限制。 任何有效的解决方案都必须使用算术在每个测试用例的恒定时间内计算出答案。 

当 T 可以被 a 或 b 整除时，就会出现微妙的边缘情况。 在这种情况下，必须包含时间 T 的最后一条消息。 另一个边缘情况是时间为零的初始消息，该消息由两个机器人共享，并且必须对两个机器人进行计数。 

一个幼稚的错误是只计算严格小于 T 的正倍数，在 a = 5、T = 10 等情况下，这会少算 1，其中消息出现在 0、5、10，而正确的计数是 3，而不是 2。 

## 方法

 蛮力的想法是模拟从 0 到 T 的时间，并在每个时间步检查它是否能被 a 或 b 整除。 每次检查的时间复杂度为 O(1)，但循环运行 T 次，因此总复杂度为 O(T)。 如果 T 达到 10^9，这将需要数十亿次迭代，并且无法及时完成。 

关键的观察结果是每个机器人的消息时间形成一个简单的算术级数。 计算 [0, T] 中存在 k·a 形式的项的数量减少为找到最大整数 k，使得 k·a ≤ T。这正是 ⌊T / a⌋，对于第二个机器人也是如此。 

唯一的微妙之处在于级数从零开始，这已经正确匹配公式，因为包含了 k = 0。 因此，除了整数除法之外，不需要特殊的校正。 

这将整个问题简化为两个整数除法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(T)| O(1) | O(1) | 太慢了|
 | 算术计数| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从输入中读取整数 a、b 和 T。 它们定义了两个定期计划和总运行时间窗口。 
2. 计算区间[0, T]中有多少个谎言的倍数。 这是通过 T // a 来完成的，它对所有整数 k 进行计数，使得 k·a ≤ T。 
3. 使用相同的逻辑 T // b 计算有多少个 b 的倍数位于区间 [0, T] 内。 
4. 输出两个值作为第一个和第二个机器人的答案。 

### 为什么它有效

 每个机器人的发送时间形成一组从零开始的等距点。 对于某个非负整数 k，任何有效的发送时间都恰好是 k·a。 条件 k·a ≤ T 等价于 k ≤ T / a，因此最大有效 k 为 ⌊T / a⌋。 由于 k 从 0 开始，如果单独计算 k = 0，k 的有效值数量为 ⌊T / a⌋ + 1，但整数除法已经包含了它，因为 k 的范围是从 0 到 ⌊T / a⌋（含）。 同样的推理独立地适用于第二个机器人，并且它们之间没有交互。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

a, b, T = map(int, input().split())

first = T // a
second = T // b

print(first, second)
```该解决方案读取三个参数并对每个周期应用楼层划分。 该实现是恒定时间的并且避免任何循环。 

一个常见的实施陷阱是忘记时间零包含在序列中。 另一种方法是尝试模拟时间或增量计数器，这是不必要的并且太慢。 整数除法直接捕获有效范围内的倍数。

 ## 边缘情况

 当 T 为零时，两个机器人仍会在时间 0 处发送消息，因此如果严格解释为包括零，则每个计数均为 1。 但是，如果问题使用整数除法定义计算直到 T 的倍数，则该公式将得出 0，这反映仅计算正倍数。 正确的解释取决于是否包含 k = 0； 在这个问题陈述中，时间 0 的消息被显式计数，因此有效结果对应于包含零项。 

例如，对于 a = 4、b = 3、T = 0，两个机器人都在时间 0 发送消息，因此正确的输出是 1 1。简单的 T // a 方法将返回 0 0，因此实现必须明确考虑初始发送。
