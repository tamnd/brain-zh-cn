 ## 解决方案
 ## 问题理解

 我们得到两个由小写字母组成的字符串。 将第一个字符串视为 Bob 生成的一长串字符，将第二个字符串视为 Alice 认为在 Bob 修改后应保留的较短字符串。 

Bob 可以从他的字符串中删除字符，但只能以一种非常特定的方式：他一次重复删除两个相邻的字符。 每次删除都会删除一个连续的对并缩短字符串。 执行此操作任意多次后，问题是该字符串是否可以变得与目标字符串完全相等。 

所以任务不是任意删除。 我们只允许以大小为二的块擦除字符串，并且总是从当前字符串的相邻位置开始。 我们必须确定是否存在将原始字符串转换为目标字符串的此类删除序列。 

这些限制允许字符串最多包含 200,000 个字符。 这立即排除了任何显式模拟删除或尝试探索所有删除序列的解决方案，因为即使是线性数量的分支选择也会以组合方式爆炸。 有效的解决方案必须接近线性时间。 

一个微妙的边缘情况来自于理解“相邻删除”的真正含义。 很容易假设删除的顺序严重限制了最终的结构，但关键的观察是，无论字符内容如何，​​删除都可以用于消除任何偶数大小的剩余部分，只要这些字符可以通过重复的邻接减少来配对。 

例如，如果选择目标字符串作为子序列后，剩余的字符形成任意长度的偶数字符串，则该剩余字符始终可以完全删除：

 输入：```
abac
a
```这里我们保留“a”并删除“bac”。 删除的部分的长度为 3，这是奇数，因此无法使用配对删除将其完全删除。 即使“a”是有效的子序列，这也会强制拒绝。 

天真的思维的主要失败模式是假设我们需要模拟删除过程本身。 这会导致复杂的堆栈模拟或区间DP，这是不必要的。 

## 方法

 暴力方法将尝试模拟相邻对删除的所有可能序列。 在每一步中，我们都可以选择任何相邻的对并将其删除，生成一个新的字符串。 这会产生巨大的分支因子，即使对于中等长度，状态数量也会呈指数级增长。 对于20万个字符来说，这是完全不可能的。 

一种更有条理的尝试是扭转这个过程。 而不是从中删除对`s`达到`t`，我们可以考虑选择哪些角色存活下来。 幸存的角色必须按顺序出现，所以`t`必须是一个子序列`s`。 选择这些角色后，其他所有内容都会成对删除。 

关键的见解是，基于邻接的删除并不限制“从长远来看哪些字符可以一起删除”。 通过重复删除相邻的对，任何偶数长度的字符串都可以完全减少为空。 我们从不需要这些对在值上匹配，只需要在删除时相邻。 由于我们总是可以在本地重新排序删除以将元素组合在一起，因此长度奇偶校验成为完全删除的唯一限制。 

所以问题减少到两个检查：

 首先，验证一下`t`可以作为子序列获得`s`。 

其次，保证剩余字符数，`|s| - |t|`，是偶数。 如果是偶数，则始终可以使用相邻删除来完全消除剩余的字符串。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力删除模拟| 指数| O(n) | 太慢了|
 | 后续检查+奇偶条件| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们使用线性扫描和两个指针来处理两个字符串。 

1. 遍历`s`从左到右，同时尝试匹配字符`t`为了。 每次我们看到一个角色`s`等于当前需要的字符`t`，我们将指针前进`t`。 这检查是否`t`是一个子序列`s`。 这样做的原因是删除仅删除字符，因此保留剩余字符的相对顺序。 
2. 扫描完成后，检查是否有所有字符`t`已匹配。 如果没有的话就没有办法获得`t`，因为删除不能创建新字符或对现有字符重新排序。 
3. 计算删除的字符数：`len(s) - len(t)`。 这表示必须通过相邻对操作删除多少个字符。 
4. 检查该数字是否为偶数。 如果很奇怪，请立即拒绝。 原因是每个操作恰好删除两个字符，因此删除的字符总数必须能被 2 整除。 
5. 如果两个条件都满足，则接受转换。 

### 为什么它有效

 子序列条件捕获了这样一个事实：删除永远不会改变保留字符之间的相对顺序。 奇偶校验条件捕获了这样一个事实：删除操作每次都会将字符串大小减少两倍，并且任何偶数长度的字符串始终可以通过重复相邻删除来减少为空。 结合这两个条件充分描述了当`t`可以从`s`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()
    
    n, m = len(s), len(t)
    
    j = 0
    for i in range(n):
        if j < m and s[i] == t[j]:
            j += 1
    
    if j != m:
        print("NO")
        return
    
    if (n - m) % 2 != 0:
        print("NO")
        return
    
    print("YES")

if __name__ == "__main__":
    solve()
```该解决方案首先执行贪婪的子序列扫描。 指针`j`仅当我们成功匹配下一个所需字符时才会前进`t`。 如果我们到达终点`t`，我们知道它嵌入在`s`为了。 

第二个检查强制要求删除的数量与删除对兼容。 由于每个操作恰好删除两个字符，因此我们需要长度的均匀差异。 

不需要模拟删除过程，这使得解保持线性。

 ## 边缘情况

 一种边缘情况是两个字符串相同。 该算法立即接受，因为子序列检查很容易通过，并且长度差为零，这是偶数。 无需删除，答案是正确的。 

另一个边缘情况是当`t`是空的。 子序列条件总是通过，答案仅取决于是否`|s|`是均匀的。 如果`s`长度为奇数，一个字符将保持不可删除，所以答案是`NO`。 该算法通过奇偶校验正确地捕获了这一点。 

最后一个边缘情况是`t`是有长度的`|s| - 1`。 即使`t`是有效子序列，差值为1，为奇数，强制拒绝。 这与使用配对操作无法删除单个剩余字符的事实相匹配。
