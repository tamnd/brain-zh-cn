 ## 问题理解

 我们的任务是分发有限数量的许愿卡$n$让小A的累计幸福感最大化。 各位朋友$i$最多可以携带$a_i$牌，所有牌的总和不能超过$k$。 幸福感是按顺序测量的：$j$第-个朋友送出了卡片，小A的幸福感增加了迄今为止送出的最多卡片数量，$\max(b_1, \dots, b_j)$。 输出就是所有朋友都送完卡后的总幸福感。 

约束条件意味着$n$可以达到$10^5$，但是卡片总数$k$很小（最多 360）。 这种差异表明算法迭代友元$O(n)$时间是可以接受的，但是任何指数级的东西$n$是不可行的。 总和$k$所有测试用例的总和也很小，这暗示了动态规划的适用性，其状态取决于剩余的卡片数量。 

非明显的边缘情况包括一些朋友无法携带任何卡或总金额的情况$k$小于最大单体容量$a_i$。 例如，如果$n = 3$,$k = 2$， 和$a = [5,0,1]$，将所有 2 张卡片交给第一个朋友是最佳选择，即使第一个朋友可以携带更多。 总是给每个朋友最大允许的天真的方法会超过$k$，产生无效的分配。 

## 方法

 暴力方法是枚举所有分配方法$b_i \le a_i$这样$\sum b_i \le k$并计算每项任务的幸福感。 每个序列都需要$O(n)$评估时间，并且序列的数量是组合的$k$和$n$，可以达到$O(n^k)$在最坏的情况下。 和$k$到了360，这个办法就行不通了。 

关键的见解是$k$小，所以我们可以设计一个动态规划解决方案，其中状态是已经使用的卡片数量和当前对幸福感的最大贡献。 让$dp[j]$代表精确使用可实现的最大累积幸福感$j$牌。 为每一位朋友$i$，我们考虑给他们$0 \le x \le \min(a_i, k)$卡并相应地更新 DP 表。 这是有效的，因为迄今为止幸福感增加了最大值，因此我们可以为每个可能使用的卡片总数保持持续的贡献。 该问题简化为小容量上的无界背包式 DP$k$，但有一点不同的是，每个朋友都会根据迄今为止给出的最大值逐步为幸福做出贡献。

 ## 算法演练

 1.初始化一个大小为DP的数组$k+1$， 在哪里$dp[j]$存储使用可实现的最大幸福感$j$牌。 将所有条目设置为负无穷大，除了$dp[0] = 0$因为使用零张卡片带来的幸福感为零。 
2. 迭代每个朋友$i$为了。 对于每个可能的卡片数量$x$那个朋友$i$可以采取，$0 \le x \le \min(a_i, k)$，按照已用卡的相反顺序更新DP表。 这确保了每个状态都正确使用前一个朋友的值。 
3. 每张已用卡总数$j$从$k$下降到$x$，计算新的幸福感为$dp[j-x] + x \cdot \max(x, m)$， 在哪里$m$代表给之前好友的最大卡数。 更新$dp[j]$如果这个新值更高。 
4. 处理完所有好友后，答案就是其中的最大值$dp[0\ldots k]$。 

保证正确性的不变量是$dp[j]$始终保持最大可实现的幸福感$j$与第一张卡$i$朋友们。 通过考虑每个好友的所有可能分配（最多可达其容量）并反向更新 DP，我们确保不会过早跳过或覆盖任何状态。

## 工作示例

 考虑第四个示例输入：$n = 5$,$k = 8$,$a = [2,4,5,4,3]$。 我们初始化`dp[0] = 0`。 处理第一个容量为2的朋友，`dp`更新为提供 0、1、2 卡。 到目前为止最大的幸福度是2。在第二个容量为4的朋友之后，给出0,1,2,3,4张牌，`dp`更新以包括像 [2,4] 这样的序列，它产生累积幸福感 2+4=6。 继续遍历所有朋友，最优分配是 [2,0,5,0,0]，产生累积幸福度 19，与预期输出相符。 

第二条踪迹：$n = 3$,$k = 4$,$a = [0,0,1]$。 只有最后一个朋友可以携带卡片。 将 1 张卡分配给最后一个朋友。 此时幸福值为 1，总幸福值为 1。即使大多数朋友的容量为零，算法也能正确识别最佳分配。
