 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并且允许我们重复执行定时操作。 在$x$- 第二秒，我们可以选择索引的任何子集并添加相同的值$2^{x-1}$到所有选定的位置。 每一秒都会给我们一个新的“二的幂”增量，我们可以将其独立应用于任何位置。 

目标不是通过交换元素对数组进行排序，而是增加选定的元素，以便在几秒后数组变得不减少。 我们希望在它成为可能之前需要最少的秒数，假设我们可以在每一秒选择最佳的索引子集。 

这些限制意味着需要高度优化的解决方案。 所有测试用例的总长度可达$10^5$，因此必须避免每个测试用例超过线性或线性算数的任何方法。 由于每个元素都会受到指数增长增量的影响，因此随着时间的推移，简单的模拟是不可能的，因为每个步骤中添加的值都会加倍，并且步骤数可能很大。 

一个关键的困难是我们并不被迫使用所有增量； 相反，我们决定如何随着时间的推移在各个位置上分配位（2 的幂），以便最终值变得不减。 

当数组已经非递减时，会出现微妙的边缘情况。 在这种情况下，答案为零，因为不需要任何操作。 

当局部下降幅度较小但需要多个位来修复时，会出现另一种边缘情况。 例如，数组早期的小违规可能仍然需要几秒钟，因为必须有较高位来修复进位约束，而不破坏早期的更正。 

最后，一个常见的陷阱是假设每一秒都贪婪地修复第一个反转。 这会失败，因为操作是累积的并影响所有未来的约束。 

## 方法

 蛮力的观点是一秒一秒地模拟。 每一秒$x$，我们尝试索引的所有子集，这已经是$2^n$选择，每个选择都会修改数组。 即使我们简化并只考虑“最佳选择”，我们仍然必须跟踪每个位级别如何有助于修复排序约束。 由于秒数可能很大，可能达到解决最坏情况差异所需的位数，因此模拟变得不可行。 

关键的见解是扭转观点。 我们不考虑时间和操作，而是将每个位置解释为累积附加值的二进制表示。 每一秒贡献一个可以独立分配给每个索引的位。 

这意味着之后$T$秒，每个元素可以增加任意数字，其二进制表示适合$T$位，但有一个限制，即每个位级别都可以独立分配给每个位置。 

现在问题变成：最小的是什么$T$这样我们就可以分配$T$-bit 递增到每个元素，以便生成的数组不减？ 

我们从左到右处理数组，并维护“需要”多少位级别，以确保在所有可能的未来分配之后当前元素至少与前一个元素一样大。 每当发生减少时，我们都会计算需要多少位来补偿该不足。 答案就是所有前缀约束所需的最大位数。 

这导致所需位容量的贪婪传播：每次反转都迫使我们“花费”更高的两层幂，直到可以补偿差异。

 ## 算法演练

 我们从左到右处理数组，同时维护一个表示当前“有效高度”和到目前为止所需位数的变量。 

1. 初始化变量`cur`作为最后处理的元素的当前调整值，以及`T = 0`表示到目前为止所需的秒数（位）。 
2. 从索引 1 开始从左到右迭代数组。在每一步中，将当前值与先前的有效值进行比较。 
3. 如果当前值已经大于或等于`cur`，我们只需设置`cur`到这个值。 没有引入新的约束，因此不需要额外的位。 
4. 如果当前值小于`cur`，我们计算差异$d = cur - a[i]$。 这种差异代表了我们必须能够使用未来的比特添加来“向上编码”多少。 
5.确定需要多少位来表示$d$。 由于每一秒都会增加 2 层的新幂，因此我们至少需要$\lceil \log_2(d+1) \rceil$秒能够弥补这一差距。 
6. 更新$T$是其当前值和所需位的最大值。 然后更新`cur`反映我们现在可以举起的事实$a[i]$使用可用位容量来匹配先前的值。 
7. 继续直到数组末尾。 最终的答案是$T$。 

### 为什么它有效

 核心不变量是处理后索引$i$，我们已经确定了所需的最小位层数，以便$a[0..i]$可以仅使用每个位置的独立位分配来实现非递减。 职位的任何减少$i$迫使我们确保存在足够的二进制“高度”来弥补差距，而未来的头寸无法降低这一要求，因为所有操作只会增加价值。 因此，超过所有局部约束的最大比特要求是充分且必要的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        T = 0
        cur = a[0]

        for i in range(1, n):
            if a[i] >= cur:
                cur = a[i]
            else:
                diff = cur - a[i]
                need = diff.bit_length()
                T = max(T, need)
                cur = cur  # stays as reference level

        print(T)

if __name__ == "__main__":
    solve()
```解决方案保持运行参考值`cur`，它代表迄今为止所需的最高基线。 当新元素较小时，我们使用以下方法计算需要多少个二进制层来弥补差距`bit_length`，它直接对应于$\lceil \log_2(d+1) \rceil$。 

变量`T`跟踪最大此类要求，因为一旦任何地方需要一定的位深度，所有较早的秒数也必须全局可用。

 ## 边缘情况

 单元素数组始终返回零，因为没有排序约束。 该算法立即设置`cur`并且永远不会进入校正状态，因此不会触发任何位要求。 

对于已经排序的数组，例如`1 2 3 4`，每次比较都通过而不会触发赤字，所以`T`始终保持为零。 这证实了算法在不需要校正时不会高估。 

对于急剧下降，例如`10 1`，差值是 9，需要 4 位，因为$9$二进制是$1001$。 算法正确计算`diff.bit_length()`如 4 和更新`T`因此。 

对于混合序列，每次阵列低于先前建立的最大值时，都会在本地重新计算所需的位深度，并且全局最大值确保最终答案反映遇到的最困难的约束。
