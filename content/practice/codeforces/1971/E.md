 ## 解决方案
 ## 问题理解

 我们有一辆汽车从位置沿直线移动`0`定位`n`。 我们知道汽车通过几个检查站的确切时间。 这些检查点按位置排序：`0, a1, a2, ..., ak`，相应的时间也严格递增：`0, b1, b2, ..., bk`，最终检查点位于位置`n`。 

在任意两个连续的已知检查点之间，汽车以恒定速度移动。 这意味着运动在时间上是分段线性的：每个段内的位置随着时间线性增加，但速度可以在给定点的边界处改变。 

对于每个查询位置`d`，我们必须计算汽车到达的时间`d`，并输出该时间的整数部分。 

主要的困难在于`n`，坐标可以大到1e9，所以我们不能一步一步地模拟运动。 然而，已知段的数量`k`每个测试最多 1e5，并且测试的总数也是 1e5，因此我们可以为每个测试用例进行对数或线性预处理。 

一个幼稚的错误源于对已知点之间插值如何工作的误解。 时间与索引不成正比，而是与段内的距离成正比。 

例如，如果我们有积分`(0, 0)`和`(10, 10)`和一个查询`d = 5`，答案是`5`。 但如果我们把第二点改成`(10, 20)`，速度加倍，所以`d = 5`对应于时间`10`。 任何假设全局速度恒定的解决方案都会失败。 

另一个微妙的边缘情况是在已知检查点精确查询。 如果`d = a[i]`，答案必须准确无误`b[i]`。 任何插值公式必须保持边界一致性。 

最后，查询可以在零之后的第一个检查点之前或任何段内着陆，因此我们必须正确定位每个查询的段。 

## 方法

 暴力方法独立处理每个查询。 对于查询位置`d`，我们扫描这些段`[a[i], a[i+1]]`, 找到哪里`d`谎言，并使用线性插值计算时间。 

在路段内，如果汽车从`(a[i], b[i])`到`(a[i+1], b[i+1])`，则速度为`(a[i+1] - a[i]) / (b[i+1] - b[i])`。 我们将其反转以计算时间`d`：```
t = b[i] + (d - a[i]) * (b[i+1] - b[i]) / (a[i+1] - a[i])
```这是正确的，但对于每个查询，我们可能会扫描最多`k`段，使得复杂性`O(kq)`每个测试用例。 和`k, q`直到 1e5，在最坏的情况下这会变成 1e10 操作，这太慢了。 

关键的观察结果是，两者`a`和`b`是排序的，并且从位置到时间的映射是单调且分段线性的。 一旦我们找到了查询位置的正确段`d`，答案是确定性的。 这将问题简化为有效的段定位。 

我们可以对`a`查找最后一个检查点的数组`a[i] ≤ d`。 之后，我们在常数时间内使用插值公式计算答案。 

因此，每个查询变成`O(log k)`而不是`O(k)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力扫描| O(kq) | O(k) | 太慢了 |
 | 二分查找+插值 | O(q log k) | O(q log k) | O(k) | 已接受 |

 ## 算法演练

 我们通过存储数组来预处理每个测试用例`a`和`b`。 

1. 读取数组`a`和`b`代表位置-时间检查点。 这些定义了从位置到时间的分段线性函数。 
2. 对于每个查询`d`，我们找到最大的索引`i`这样`a[i] ≤ d`。 这标识了包含以下内容的段：`d`因为该函数的位置是单调的。 
3.如果`d`等于检查点`a[i]`，我们直接返回`b[i]`。 这可以避免浮点错误并保留已知点的精确值。 
4. 否则，我们计算路段内行驶距离的分数：

 段内的相对位置是`(d - a[i]) / (a[i+1] - a[i])`。 
5. 我们使用线性插值将该分数映射到时间空间：`t = b[i] + (d - a[i]) * (b[i+1] - b[i]) // (a[i+1] - a[i])`。 

使用整数除法是因为输出需要时间的下限。 
6. 打印计算出的时间。 

### 为什么它有效

 在每个段内，位置是时间的线性函数，因为速度是恒定的。 这意味着从位置到时间的逆映射在相同的间隔上也是线性的。 自从`a`严格递增，每个位置`d`恰好位于一个段中，并且二分查找可以正确识别该段。 插值公式精确地重建了限制于该段的逆线性函数，因此计算出的时间与真实的连续时间相匹配，并得出所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, q = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        for _ in range(q):
            d = int(input())

            if d <= a[0]:
                if a[0] == 0:
                    print(0)
                else:
                    # segment from 0 to a[0]
                    dt = b[0] * d // a[0]
                    print(dt)
                continue

            if d >= a[-1]:
                print(b[-1])
                continue

            lo, hi = 0, k - 1
            while lo < hi:
                mid = (lo + hi) // 2
                if a[mid] <= d:
                    lo = mid + 1
                else:
                    hi = mid
            i = lo - 1

            if a[i] == d:
                print(b[i])
            else:
                dt = (b[i+1] - b[i]) * (d - a[i]) // (a[i+1] - a[i])
                print(b[i] + dt)

solve()
```该实现依赖于二分搜索来有效地找到正确的段。 边缘情况`d <= a[0]`单独处理，因为第一段隐式从零开始。 对于超出最后一个检查点的查询，答案是直接`b[k-1]`因为车已经到达目的地了。 

插值完全用整数完成，并且在除法之前执行乘法以保持精度。

 ## 边缘情况

 一个重要的边缘情况是查询位于第一个已知检查点之前。 在该区域中，我们有效地从`(0, 0)`到`(a[0], b[0])`。 例如，如果`a[0] = 10`和`b[0] = 5`， 然后`d = 2`给出`t = 5 * 2 // 10 = 1`。 该实现显式处理此问题，而无需输入二分搜索，因为没有先前的段。 

另一个边缘情况是检查点处的精确匹配。 如果`d = a[i]`，插值仍然可以进行数值计算，但它存在舍入误差和不必要的计算的风险。 直接返回`b[i]`确保正确性并避免划分伪影。 

最后一个边缘情况是查询超出最后一个检查点。 自从`a[k-1] = n`， 任何`d ≥ n`必须返回`b[k-1]`。 该解决方案直接处理这个问题，反映运动不会继续超过最终的已知时间点。
