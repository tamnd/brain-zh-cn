 ## 解决方案
 ## 问题理解

 我们正在处理 12 个等距点的圆形排列，标记为 1 到 12，就像时钟上的小时一样。 每个测试用例给出四个不同的标签 a、b、c、d。 Alice 在 a 和 b 之间画一个直和弦，Bob 在 c 和 d 之间画另一个和弦。 任务是确定这两个弦是否在圆内相交。 

从几何角度来看，这与通常的欧几里得意义上的距离或角度无关，而是与圆形顺序有关。 当且仅当我们绕圆走时，两条弦的端点交错时，两条弦才相交。 

约束很小：最多 5940 个测试用例，固定的宇宙大小为 12 个点。 这立即排除了任何繁重的每次测试计算，但也表明期望每次测试进行恒定时间或简单的组合检查。 每个测试超出 O(t) 或 O(1) 的任何内容仍然可以轻松通过，但预期的解决方案纯粹是逻辑性的，而不是计算密集型的。 

如果我们尝试将数字视为线上的点，就会出现一个微妙的问题。 例如，弦 (1, 8) 和 (2, 10) 在数轴上看起来不相交，但在圆上它们确实相交，具体取决于顺序。 另一个常见的错误是忘记和弦是无向的，因此 (a, b) 与 (b, a) 相同。 如果我们无法标准化排序，区间推理就会变得不一致。 

## 方法

 思考这个问题的一种强力方法是几何模拟。 我们可以用坐标对圆上的 12 个点进行建模，为两个弦绘制线段，并使用方向测试检查线段是否相交。 这可以通过将每个弦视为 2D 中的一段并应用段相交逻辑来实现。 每个测试都需要恒定的时间，但实现比必要的更繁重，并且引入了浮动或坐标簿记。 

关键的观察是我们永远不需要几何。 我们只关心循环顺序。 修复一个和弦，例如（a，b）。 该弦将圆分成两条弧。 任何其他弦 (c, d) 与它相交当且仅当 c 和 d 位于该分割的不同侧。 换句话说，第二弦的一个端点位于a和b之间的一条弧上，另一端点位于相反的弧上。 

为了使这一点更加精确，我们通过选择第一个弦的一个端点并顺时针行走直到另一个端点来线性化圆。 这定义了循环排列上的间隔。 如果第二弦的端点之一正好位于该区间内，则第二弦相交。 这将问题转换为循环排序中的简单成员资格检查。 

因为宇宙大小是固定的且很小，所以我们可以使用模运算或显式模拟圆来直接计算“a 和 b 之间的 x 顺时针方向”。

 ## 算法演练

 我们首先定义一个辅助概念：给定圆上的两个点 a 和 b，我们想知道第三个点 x 是否严格位于从 a 到 b 的顺时针圆弧上。 

我们可以通过沿着圆圈 1 → 2 → ... → 12 → 1 从 a 走到 b 来实现这一点，标记访问过的区域。

1. 固定第一弦端点a和b。 我们概念性地定义从a到b的顺时针弧。 如果需要，我们可以通过将圆视为模 12 来确保方向一致。 
2. 构建一个隶属度测试，确定点 x 是否严格位于该弧内，不包括 a 和 b 本身。 这是通过从 a 向前迭代直到到达 b 来完成的。 
3. 对于第二弦端点 c 和 d，检查 c 或 d 之一是否正好位于圆弧 (a, b) 内。 
4. 如果正好有一个端点在内部，则弦必须交叉。 否则，它们不相交。 

这种逻辑起作用的原因是，一个弦与圆中的第二个弦相交相当于端点按循环顺序交替。 如果一个弦的两个端点位于另一个弦引起的分裂的同一侧，则可以绘制线段而不交叉。 如果它们被裂缝分开，则圆内的任何直线实现都会强制相交。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def in_arc(a, b, x):
    # check if x is strictly between a and b clockwise
    cur = a
    while True:
        cur = cur + 1
        if cur == 13:
            cur = 1
        if cur == b:
            return False
        if cur == x:
            return True

t = int(input())
for _ in range(t):
    a, b, c, d = map(int, input().split())

    # normalize direction doesn't matter due to symmetric check
    inside_c = in_arc(a, b, c)
    inside_d = in_arc(a, b, d)

    if inside_c ^ inside_d:
        print("YES")
    else:
        print("NO")
```实现的核心是`in_arc`函数，它显式地沿着圆从 a 走到 b。 由于圆的大小固定为 12，因此即使将其写为循环，该操作实际上也是恒定时间。 

异或条件`inside_c ^ inside_d`编码要求恰好有一个端点位于弧内。 这是相交的精确条件。 

一个常见的陷阱是尝试将间隔视为简单的数字范围。 从模块化意义上来说，当 a > b 时，就会失败，因为圆是环绕的。 显式遍历避免了整类错误。

 ## 边缘情况

 关键的边缘情况是第一个弦非常短，例如 a 和 b 相邻。 例如，输入 a = 1、b = 2、c = 3、d = 4 会生成空的内部弧。 运行算法，`in_arc(1,2,3)`和`in_arc(1,2,4)`两者都返回 false，因为循环立即到达 b。 由于两个端点都不在内部，因此 XOR 为 false，输出为 NO，与几何形状匹配。 

另一种情况是环绕行为，例如 a = 12 和 b = 3。弧为 12 → 1 → 2 → 3。如果 c = 1 且 d = 10，则 1 在弧内，而 10 在弧外，因此算法返回 YES。 显式循环遍历保证了正确处理环绕，而无需特殊的大小写算术比较。 

第三个微妙的情况是对称性：交换和弦的端点不应改变答案。 因为我们从不假设 a 和 b 之间或 c 和 d 之间的排序，所以无论输入顺序如何，隶属度测试都保持一致。
