 ## 解决方案
 ## 问题理解

 我们正在查看平面上的整数网格点，每个点都有坐标$(x, y)$其中两个值都是整数。 对于每个测试用例，半径$r$给定后，我们需要计算以原点为中心的细圆环中有多少个格点。 

如果一个点到原点的欧氏距离至少为$r$并且严格小于$r+1$。 用代数术语来说，对于一个点$(x, y)$，我们计算如果$$r^2 \le x^2 + y^2 < (r+1)^2.$$因此，问题是要求平方距离落在两个连续圆之间的特定环内的整数网格点的数量。 

输入大小建议最多 1000 个查询，所有查询的总和$r$值高达$10^5$。 这排除了为每个测试用例在整个网格上重新计算的任何内容。 对正方形边进行简单扫描$2r$会花费$O(r^2)$，当$r$达到$10^5$。 

一个关键的微妙之处在于，这不是一个连续的几何问题，而是一个离散的计数问题。 小变化$r$不要平滑地改变答案，并且精确整数处的边界行为很重要，因为我们正在处理整数平方。 

一个常见的失败案例来自于尝试近似面积差异。 例如，使用$\pi((r+1)^2 - r^2)$给出$2\pi r + \pi$，这接近答案但不准确。 为了$r=1$，这个近似给出了关于$3\pi \approx 9.4$，而真实答案是 8。不匹配是由于圆边界附近的晶格不规则性造成的。 

另一个失败案例是错误地重复计算对称性。 人们可能会计算一个象限中的点并乘以四，但轴上的点的行为不同，并且环边界破坏了均匀对称性。 

## 方法

 暴力破解的想法很简单：枚举所有整数对$(x, y)$和$|x| \le r+1$和$|y| \le r+1$, 计算$x^2 + y^2$，并检查是否在区间内$[r^2, (r+1)^2)$。 这是正确的，因为它直接实现了定义。 然而，它粗略地检查$(2r+2)^2 \approx 4r^2$每个测试用例的点数，这对于$r = 10^5$。 

关键的观察是条件仅取决于$x^2 + y^2$，所以问题是径向对称的。 我们可以迭代可能的整数，而不是迭代点$x$值并计算有效范围$y$每个值$x$。 对于固定的$x$，不等式变为：$$r^2 - x^2 \le y^2 < (r+1)^2 - x^2.$$这将问题转化为计算整数$y$平方区间内的值，可以使用整数平方根计算。 每个$x$贡献有效点的垂直切片，我们只需要对所有点求和$x$从$-(r+1)$到$r+1$，即$O(r)$。 

这是有效的，因为总和$r$跨测试用例的边界为$10^5$，因此每个测试用例的迭代总体上仍然是线性的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(r^2)$每次测试|$O(1)$| 太慢了 |
 | 最佳 |$O(r)$每次测试|$O(1)$| 已接受 |

 ## 算法演练

 我们用计算整数的方式重写这个问题$y$每个固定值$x$。 

1. 对于每个具有半径的测试用例$r$，我们迭代$x$从$-(r+1)$到$r+1$。 

这个范围就足够了，因为超出这个范围，即使$y=0$会给$x^2 \ge (r+1)^2$，所以没有点可以满足条件。 
2.对于每个固定$x$，计算下限和上限$y^2$：$$L = r^2 - x^2,\quad U = (r+1)^2 - x^2.$$这些代表了允许的范围$y^2$。 
3.如果$U \le 0$，没有整数$y$为此工作$x$，所以我们跳过它。 

即使是最大可能的情况下也会发生这种情况$y^2$太小，无法到达内圈。 
4. 夹钳$L$至少为 0，因为$y^2$不能为负数。 

负下限会错误地允许所有小$y$，所以我们纠正它们。 
5. 将平方范围转换为整数范围$y$：$$|y| \in [\lceil \sqrt{L} \rceil, \lfloor \sqrt{U-1} \rfloor].$$我们计算：$$y_{\min} = \lceil \sqrt{L} \rceil,\quad y_{\max} = \lfloor \sqrt{U-1} \rfloor.$$6. 计算有效整数$y$在这个范围内。 每个有效幅度贡献两个对称点（$+y$和$-y$）， 除了$y=0$计算一次。 

我们使用间隔长度仔细计算，避免重复计算。 
7. 总捐款额$x$，产生最终答案。 

### 为什么它有效

 该算法将所有格点按它们的$x$-协调。 对于每个固定$x$，每个有效点对应一个$y$满足连续不等式$y^2$。 由于平方在非负整数上是单调的，因此有效$y$值形成两个对称区间$[-k, -m]$和$[m, k]$，或者可能为空。 通过将平方边界转换为整数根边界，我们可以准确地捕获所有整数解，而不会遗漏或重叠。 每个格点都有一个$x$切片，因此对切片求和只会对每个点计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def isqrt(x):
    # integer square root (safe fallback using binary search)
    lo, hi = 0, x
    while lo <= hi:
        mid = (lo + hi) // 2
        if mid * mid <= x:
            lo = mid + 1
        else:
            hi = mid - 1
    return hi

def count_y(L, U):
    # count integers y such that L <= y^2 < U
    if U <= 0:
        return 0
    if L < 0:
        L = 0

    # y^2 < U  => |y| <= floor(sqrt(U-1))
    r = isqrt(U - 1)
    # y^2 >= L => |y| >= ceil(sqrt(L))
    l = isqrt(L)
    if l * l < L:
        l += 1

    if l > r:
        return 0

    # count integers in [-r, -l] and [l, r]
    # careful with zero
    total = 2 * (r - l + 1)
    if l == 0:
        total -= 1
    return total

t = int(input())
for _ in range(t):
    r = int(input())
    ans = 0

    rr = r * r
    rp = (r + 1) * (r + 1)

    for x in range(-(r + 1), r + 2):
        x2 = x * x
        L = rr - x2
        U = rp - x2
        ans += count_y(L, U)

    print(ans)
```核心结构迭代所有可能的$x$-可能与环面相交的坐标。 对于每个$x$，它将 2D 条件转换为 1D 约束$y^2$，然后使用平方根边界计算有效整数解。 

最微妙的部分是正确处理包容性。 外边界严格小于$(r+1)^2$，这强制使用$U-1$当转换为整数平方根时。 内部边界是包容性的，这就是为什么$L$不以同样的方式移动。 

对称处理嵌入到计数函数中：而不是单独迭代正负$y$，我们计算绝对值的范围并将它们转换回整数计数。

 ## 边缘情况

 对于$r = 1$，有效点满足$1 \le x^2 + y^2 < 4$。 算法检查$x \in [-2, 2]$。 为了$x=0$，它计算$y^2 \in [1,4)$，生产$y = \pm 1$，贡献2分。 为了$x=1$，同样的情况也会发生，并且对称性使所有切片的贡献正确加倍，总共产生 8 个点。 

为了$r = 2$，算法处理$x \in [-3, 3]$。 在$x=0$，这算$y^2 \in [4,9)$, 给予$y = \pm2, \pm3$。 在$x=1$，它计算的间隔稍小一些。 外$x$值很快会产生负界并贡献为零。 这演示了该方法如何自然地修剪搜索空间而无需显式修剪，因为无效切片通过不等式处理消失。
