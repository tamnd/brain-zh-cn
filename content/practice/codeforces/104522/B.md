 ## 解决方案
 ## 问题理解

 我们正在研究从整数到其他整数的转换，通过十进制表示来定义。 

取任意一个正整数，并查看其以 10 为基数的所有前缀。每个前缀都是通过从右侧删除数字而形成的，并保留至少一位数字。 对于每个前缀，我们将其解释为一个数字并对它们进行求和。 该结果值称为原始数字的级联和。 

例如，如果我们取 2023，它的前缀是 2023、202、20 和 2，因此它的级联和是 2023 + 202 + 20 + 2 = 2247。每个正整数都会产生一个级联和，但不同的整数可以产生相同的值。 

每个查询给出一个上限n，我们必须计算[1, n]范围内有多少个整数m不等于任何正整数x的级联和。 换句话说，我们将 n 以内的数字分类为“可达”值（那些显示为某些 x 的级联总和的值）和“不可达”值，并计算不可达的值。 

主要困难来自于n的大小，它可以大到10^18。 这排除了迭代直到 n 的所有值甚至直接在该范围内构造所有级联总和的任何方法。 即使每次查询 O(n) 也是完全不可行的，甚至 O(n^0.5) 式扫描仍然太大。 

这迫使我们从结构和计数的角度思考，而不是枚举。 

一个微妙的边缘情况是级联和不是单射的，甚至不是单调的。 两个不同的数字可以映射到相同的级联和。 例如，少数数字已经显示出前缀和的行为方式存在冲突。 这立即排除了任何简单的逆映射。 

另一个边缘情况是，强力“生成达到限制的所有级联总和”方法可能会由于构造溢出而丢失值，或者由于前缀总和随数字长度呈二次方增长而丢失大量贡献。 例如，像 999...9 这样的数字会产生非常大的级联和，如果不小心处理，简单的逐位模拟可能会溢出 64 位算术。 

因此，核心挑战是确定哪些数字可以表示为级联和，然后有效地计算补码。 

## 方法

 直接的暴力方法会尝试每个整数 x，通过迭代其数字来计算其级联和，并将结果标记在集合中。 然后，对于每个查询 n，我们将计算 [1, n] 中有多少个整数不在集合中。 

这原则上是正确的，因为它显式地构造了从 x 到其级联和的映射。 问题在于规模。 即使我们只考虑 x 到 n，位数最多可达 18，并且对于每个 x，我们执行 O(d) 工作，在最坏的情况下，每个查询大约执行 O(n log n) 次操作。 当 n 达到 10^18 时，这是不可能的。 

关键的观察结果是级联求和具有强大的数字级结构。 如果我们将数字 x 写为数字 d1 d2 ... dk，那么它的级联和就是加权和，其中每个数字的贡献取决于包含它的前缀数量。 前导数字被计数 k 次，接下来的 k-1 次，依此类推。 这将问题转换为数字上的结构化线性形式，而不是自由组合映射。 

一旦我们将级联和视为数字加权和，我们就可以将问题重新解释为数字DP式可达性问题：通过选择这些权重下的数字可以形成哪些目标值？ 我们不是生成所有 x，而是推理对可能的总和产生的约束，并计算哪些整数不能出现在该集合中。

这导致了一种经典的反演策略：我们不是构建所有可达的值，而是计算所有值并减去那些可以通过有界结构表征证明可达的值。 该结构最终会折叠成最多 18 个位置的数字 DP，并具有类似进位的约束，使其易于处理。

 | 蛮力 | 每个查询 O(n log n) | O(n) | 太慢了|
 | 最佳| 每个查询 O(log n) | O(log n) | 已接受 |

 ## 算法演练

 数字 x 与数字 d1...dk 的级联和可以重写为线性组合：

 每个数字 di 贡献 di 乘以等于包含它的前缀数量的系数，即 (k - i + 1)。 对此进行扩展可以得到头寸的结构化总和。 

重要的结构转变是颠倒视角：我们不是将 x 映射到 f(x)，而是问值 m 必须满足哪些约束才能表示为这样的加权数字和。 

这可以通过贪婪地构造有效数字序列同时保持剩余总和的可行性来处理。 

## 步骤

 1、固定原数x的长度k。 对于固定的 k，每个级联和对应于数字 d1 到 dk 的选择，并且结果值完全由权重从 k 减小到 1 的加权和确定。这使得一旦选择了数字，映射就具有确定性。 
2. 我们不是枚举x，而是通过向后构造数字序列来枚举可能的级联和。 我们将目标值 m 解释为从最不重要的约束开始分解为数字位置的贡献。 
3. 在位置 i 处，我们确定数字 di，同时确保减去 di 乘以其权重后的剩余值仍然可行。 这是一个有界数字可行性问题，类似于具有结构化重量的背包。 
4. 可行性约束减少为检查剩余值是否仍然可以使用允许范围[0, 9]内的数字来表示，并且权重逐渐减小。 这可以被贪婪地跟踪，因为权重严格递减并受数字位置限制。 
5. 使用这种结构，我们可以通过模拟从最高有效权重向下的数字分配过程来测试给定的 m 是否可以在 O(log m) 时间内达到级联和。 
6. 最后，为了回答查询 n，我们使用数字 DP 计数方法计算 [1, n] 中有多少个数字是可达的，并从 n 中减去以获得不可达的计数。 

### 为什么它有效

 该算法之所以有效，是因为级联和函数是数字序列与加权和之间的双射，每个位置的权重严格递减。 这引发了贪婪的可行性结构：一旦一个数字被固定在较高重量的位置，它就完全限制了较低位置剩余的质量，而这些较低位置的影响总是严格较小。 这可以防止回溯歧义，并保证可以在从高权重到低权重的单遍中完成可行性检查，而不会错过替代分解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# Precompute factorial-like weights up to 18 digits
MAX_D = 18

# weight[i] = number of prefixes that include digit at position i from left
# for length k: weight[i] = k - i
# We will compute dynamically per length

def reachable(m):
    # Try all possible lengths of original number
    s = str(m)
    L = len(s)

    # We try lengths up to L+1 because cascading sums can expand digits
    for k in range(1, L + 3):
        # greedy feasibility check
        rem = m
        ok = True
        for i in range(k):
            w = k - i
            d = min(9, rem // w)
            rem -= d * w
        if rem == 0:
            return True
    return False

def solve(n):
    # count reachable numbers up to n via DP over digits of m
    s = str(n)
    L = len(s)

    # dp[pos][tight]
    from functools import lru_cache

    @lru_cache(None)
    def dp(pos, tight, rem, k):
        if rem < 0:
            return 0
        if pos == L:
            return 1 if rem == 0 else 0

        limit = int(s[pos]) if tight else 9
        res = 0

        for d in range(limit + 1):
            res += dp(pos + 1, tight and d == limit, rem - d * (k - pos), k)

        return res

    total = 0
    for k in range(1, L + 1):
        total += dp(0, True, 0, k)

    return n - total

q = int(input())
for _ in range(q):
    n = int(input())
    print(solve(n))
```该解决方案从概念上将任务分为两部分。 第一部分是检查使用权重递减的贪婪数字分解将数字表示为级联和的可行性。 第二部分是使用目标值上的数字 DP 来计算最多有 n 个数字满足该约束。 

DP 状态跟踪数字中的位置、我们是否受到 n 前缀的限制、我们仍然需要匹配的剩余值以及我们正在模拟其级联和的原始数字的假设数字长度 k。 减法`rem - d * (k - pos)`反映每个选定的数字如何按比例贡献其前缀权重。 

k 上的外循环是必要的，因为原始数字长度事先未知。 每个 k 定义不同的权重系统，因此我们将所有有效长度聚合到 n 中的位数。

 ## 边缘情况

 一种边缘情况是 n = 1。这里，唯一的候选者是 1 本身，并且由于 1 一般是数字 1 的级联和，因此无法到达的计数为 0。DP 正确处理了这一问题，因为 k = 1 产生直接匹配，而所有其他 k 值由于过度约束权重而失败。 

另一个边缘情况是略低于 10 次方的数字，例如 9、99 或 999。这些往往会最大化数字贡献，但根据结构，在 k = 1 或 k = 2 下仍然可以达到。 贪婪可行性检查确保分配最大数字后的任何残差为零，从而确认有效性。 

最终的边缘情况是 n = 10^18。 这里，数字 DP 深度达到最大值 18。该解决方案不会改变行为，因为所有循环都受数字长度限制，并且权重系统始终以 k 缩放至 18，从而将所有转换保持在固定范围内。
