 ## 解决方案
 ## 问题理解

 我们给定一个起始整数$x$，我们可以通过选择一个小整数来调整它$y$0到100之间。选择后$y$，我们计算数字$n = x + y$，然后形成两个值：$n^2$和$n^3$。 我们将这两个数字都写成十进制，不带前导零，并将它们连接起来。 生成的数字字符串必须包含从 0 到 9 的每个数字恰好一次。 

因此，任务不是在大范围内优化任何内容或找到数学公式。 搜索空间很小：最多 101 个候选者$y$，每个考生只需要基本的算术和数字计数。 挑战纯粹是正确模拟条件并检查候选人是否产生有效的 10 位排列。 

边界使得这个问题的计算量非常小。 即使对每个候选人进行简单的检查也是一项持续的工作，因为大约 150 的数字的平方和立方是微不足道的。 这意味着尝试所有可能性的任何解决方案都足够快，并且不需要修剪或数论技巧。 

主要的边缘情况来自格式和数字处理。 将整数转换为字符串时，前导零会自动删除，因此我们不需要显式处理它们。 然而，最常见的失败模式是通过将数字视为固定宽度来错误地计算数字，或者忘记连接是基于字符串的，而不是基于算术的。 

另一个微妙的问题是假设连接的字符串必须恰好有 10 位数字，而不验证数字的唯一性。 例如，候选人可能会生成一个 10 位数字的字符串，但仍然重复数字或丢失一位数字，这将是无效的。 

## 方法

 蛮力方法是尝试每一个可能的值$y$从 0 到 100。对于每个候选者，我们计算$n = x + y$，然后计算$n^2$和$n^3$，将两者都转换为字符串，连接它们，并检查结果字符串是否是“0123456789”的排列。 

这种方法是正确的，因为该问题保证如果存在解，则它位于允许的范围内$y$。 除了这个有界搜索之外，没有任何结构可以利用，因为从$y$由于平方和立方，数字模式是高度非线性的。 

暴力破解的成本非常小。 我们最多评估 101 个候选者，每个候选者都涉及常数时间算术和最多几个数字运算。 即使我们悲观地假设每次检查需要 O(20) 次操作，总工作量也可以忽略不计。 

除了直接枚举之外无需进行优化。 任何更复杂的方法只会使正确性变得复杂，而不会有意义地改善运行时间。

 ## 算法演练

 1. 迭代所有整数$y$从 0 到 100（含）。 每个值代表一个可能的调整$x$。 
2. 计算$n = x + y$。 这是我们将分析其平方和立方的候选基数。 
3. 计算$a = n^2$和$b = n^3$。 这些定义了我们必须连接的两个值。 
4. 转换$a$和$b$成字符串并将它们连接成一个字符串$s = str(a) + str(b)$。 这一步很重要，因为需要数字级推理，而不是算术组合。 
5. 检查是否$s$正好包含 10 个字符。 如果不是，请立即跳过该候选，因为数字 0-9 的有效排列必须具有长度 10。 
6. 验证从 0 到 9 的每个数字在$s$。 一个简单的方法是对字符串进行排序并与“0123456789”进行比较。 
7. 如果条件成立，输出$y$立即停止。 
8. 如果没有$y$在检查了所有可能性之后才起作用，问题保证这种情况不会发生，所以在实践中我们永远不会达到它。 

### 为什么它有效

 正确性依赖于问题中唯一自由度的详尽性，即$y$。 对于每位候选人$y$，我们完全确定生成的数字字符串，并根据严格的唯一性条件对其进行检查。 由于映射来自$y$由于数字集是确定性的并且搜索空间是完整的，因此在迭代过程中必须遇到任何有效的解决方案。 数字检查强制连接字符串和数字 0 到 9 之间的双射，因此任何接受的候选都保证完全满足要求。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_valid(s: str) -> bool:
    if len(s) != 10:
        return False
    return sorted(s) == list("0123456789")

def main():
    x = int(input().strip())

    for y in range(0, 101):
        n = x + y
        s = str(n * n) + str(n * n * n)
        if is_valid(s):
            print(y)
            return

if __name__ == "__main__":
    main()
```该实现是算法的直接翻译。 辅助函数隔离了数字验证逻辑，从而降低了主循环中出错的风险。 关键的微妙之处在于使用字符串排序进行验证，而不是尝试手动计算数字，这可以避免频率数组中的相差一错误。 

该循环严格限制为 101 次迭代，确保可预测的运行时间。 一旦找到有效的候选者，该函数立即返回以避免不必要的计算。

 ## 边缘情况

 一个关键的边缘情况是当$n^2$或者$n^3$分别少于 4 或 6 位数字。 例如，如果$n = 2$，我们得到$n^2 = 4$和$n^3 = 8$，生成字符串“48”。 该算法正确地拒绝了这一点，因为长度检查立即失败，从而防止任何不正确的数字排列评估。 

另一个边缘情况是两个数字之间出现重复的数字。 例如，如果候选者输出“1123456789”，它仍然有 10 位数字，但由于重复而无效。 排序比较捕获了这一点，因为排序结果与严格序列“0123456789”不匹配。
