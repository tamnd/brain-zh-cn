 ## 解决方案
 ## 问题理解

 我们有`n`铅笔颜色。 如果我们画`x_i`有颜色的鱼`i`，从该颜色获得的星星取决于有多少鱼共享该颜色。 第一条彩色鱼`i`给出`a_i`星星，第二个给出`a_i - 2`，第三个给出`a_i - 4`， 等等。 一种颜色只能使用到单条鱼的分数失效为止，这意味着该颜色的鱼的数量不能超过`a_i + 1`。 

任务是准确选择`m`鱼的总数，将它们分配给颜色，以便所有收到的星星的总和尽可能大。 我们必须输出最大分数和一个有效分布。 

这些限制迫使我们避免任何与`m`。 的价值`m`可以达到`10^9`，因此模拟每条鱼或每一种可能的选择是不可能的。 甚至`O(m)`将需要数十亿次操作。 颜色数量仅`2 * 10^5`，因此预期的解决方案必须接近`O(n log A)`在哪里`A`是可能的星值范围。 

棘手的部分是，最佳分布并不是简单地“使用最大的颜色”`a_i`第一个”。随着分配给它的鱼越多，颜色的价值就会变得越低。例如，如果`a = [5]`和`m = 3`，三条鱼给出`5`,`3`， 和`1`星星，不是三倍`5`。 

粗心的解决方案也可能在大量所需计数时失败。 例如：```
Input
1 2
1
```唯一的颜色赋予价值`1, -1, ...`。 正确的输出是：```
0
0 2
```两条鱼一起给出`1 + (-1) = 0`。 只需要积极贡献的贪婪解决方案可能会输出一条鱼，但确切地说`m`鱼必须画出来。 

另一种边缘情况是许多颜色具有相同的边缘值：```
Input
3 9
1 2 3
```正确的输出是：```
0
2 3 4
```可能存在不同的最优分布。 该算法必须在不假设唯一答案的情况下处理联系。 

## 方法

 直接的方法是查看每种可能添加的鱼。 对于颜色`i`，增益序列为：```
a_i, a_i - 2, a_i - 4, ..., -a_i
```有`a_i + 1`可能有这种颜色的鱼。 如果我们产生所有可能的收益并选择最大的`m`，该解决方案将是正确的，因为每一种鱼的选择都只贡献一个边际值。 然而，`a_i`可以大到`10^9`，所以这个序列可以包含数十亿个值。 扩展所有序列是不可能的。 

关键的观察是这些序列是排序的算术级数。 我们不需要生成它们。 我们只需要知道有多少个值至少达到某个阈值。 

假设我们选择一个值`x`。 对于一种颜色，边际增益数至少`x`可以从数学上找到。 如果我们可以计算所有颜色中有多少增益高于阈值，二分搜索可以让我们找到最大增益之间的截止值`m`收益。 

找到阈值后`t`，每个增益大于`t`必须采取，并且只有一些收益等于`t`可能需要准确地到达`m`鱼。 由于颜色中的所有增益形成递减序列，因此为每种颜色选择的增益始终形成一个前缀，这使我们能够重建每种颜色的鱼的数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(总和(a_i)) | O(总和(a_i)) | 太慢了，因为值可以达到 10^9 |
 | 最佳| O(n log A) | O(n log A) | O(n) | 已接受 |

 ## 算法演练

 1. 对于每种颜色，将鱼类可能的贡献视为递减序列：`a_i, a_i - 2, a_i - 4, ... , -a_i`。 

答案是最大的数之和`m`所有这些序列中的值。 
2. 实现一个函数，计算所有序列中有多少个值至少是给定数字`x`。 

对于一种颜色，如果`x > a_i`，不存在这样的值。 如果`x <= -a_i`， 全部`a_i + 1`值符合条件。 否则，解决：`a_i - 2k >= x`为了最大可能的`k`。 
3. 二分查找最大阈值`t`使得至少有`m`边际值大于或等于`t`。 

该阈值是最后选择的边际贡献的值。 
4. 计算所有严格大于的贡献`t`。 必须选择这些贡献，因为数量少于`m`贡献超过阈值。 
5. 添加足够的贡献，等于`t`准确地达到`m`鱼。 

对于每种颜色，首先分配所有贡献大于的鱼`t`。 然后将剩余的鱼分配给下一个可用贡献等于的颜色`t`。 
6. 将最终得分计算为所有选定边际贡献的总和，并输出分配给每种颜色的鱼的数量。 

为什么它起作用：固定颜色的每条额外的鱼的边际贡献只会减少，因此一种颜色的任何最佳选择都必须采用其序列的前缀。 整个问题变成选择最大的`m`来自排序序列的元素。 通过二分查找找到的阈值将选定值与未选定值分开。 所有高于阈值的值都是强制性的，用等于阈值的值填充剩余位置不能减少答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    def count_ge(x):
        res = 0
        for v in a:
            if x > v:
                continue
            if x <= -v:
                res += v + 1
            else:
                res += (v - x) // 2 + 1
        return res

    def sum_ge(x):
        res = 0
        for v in a:
            if x > v:
                continue
            if x <= -v:
                c = v + 1
            else:
                c = (v - x) // 2 + 1
            last = v - 2 * (c - 1)
            res += c * (v + last) // 2
        return res

    lo = -10**9 - 1
    hi = 10**9 + 1
    while lo + 1 < hi:
        mid = (lo + hi) // 2
        if count_ge(mid) >= m:
            lo = mid
        else:
            hi = mid

    threshold = lo

    ans = sum_ge(threshold + 1)
    used = [0] * n
    taken = 0

    for i, v in enumerate(a):
        if threshold + 1 > v:
            continue
        if threshold + 1 <= -v:
            c = v + 1
        else:
            c = (v - (threshold + 1)) // 2 + 1
        used[i] = c
        taken += c

    need = m - taken

    for i, v in enumerate(a):
        if need == 0:
            break
        nxt = v - 2 * used[i]
        if nxt == threshold:
            used[i] += 1
            need -= 1
            ans += threshold

    print(ans)
    print(*used)

if __name__ == "__main__":
    solve()
```这`count_ge`函数的核心是二分查找。 它从不构造序列，因为每种颜色都可以使用算术级数公式进行计数。 

这`sum_ge`函数使用相同的计数逻辑，但也会对选定的算术级数求和。 第一个值始终是`a_i`，并通过减去最后选择的值来找到`2`每一步。 

找到阈值后，重建阶段将严格高于阈值的每个贡献都考虑在内。 其余位置的值必须完全等于阈值，因此检查每种颜色的下一个未使用的贡献就足够了。 序列顺序保证再添加一条鱼始终是下一个可用的边际值。 

所有算术都是使用 Python 整数完成的，因此参与求和贡献的大型乘积不会溢出。

 ## 边缘情况

 对于这个案例：```
1 2
1
```唯一的顺序是：```
1, -1
```二分查找找到阈值`-1`。 算法取上面的值`-1`，即`1`，然后添加一个等于`-1`。 最终得分为`0`，唯一有效的分布是两条相同颜色的鱼。 

为了：```
3 9
1 2 3
```容量为`2`,`3`， 和`4`，所以必须使用所有的鱼。 选定的边际值为：```
1, -1
2, 0, -2
3, 1, -1, -3
```他们的总和为零。 该算法很自然地达到了这一点，因为阈值成为所需的最低贡献，并且它仍然尊重准确的鱼数。 

对于具有相同值的颜色，例如：```
5 14
2 2 3 2 2
```许多边际贡献是相同的。 二分查找仅确定值边界，而不确定确切的颜色。 在重建过程中，具有所需下一个贡献的任何颜色都是可接受的，这就是该方法可以输出任何最佳分布的原因。
