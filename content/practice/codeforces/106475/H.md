 ## 解决方案
 ## 问题理解

 我们给出了一组由无向道路连接的位置。 每条道路都有固定的通行时间，但由于交通信号灯在红色阶段和绿色阶段之间反复循环，因此使用起来很复杂。 

当您有时到达道路的一端时，您可能不被允许立即开始过马路。 每条道路都有重复的时间表：首先是长度为 r 的红色时段，在此期间禁止进入，然后是长度为 g 的绿色时段，在此期间允许您进入并穿过道路。 这种模式永远重复。 

如果您在绿色阶段到达，则可以立即开始。 如果您在红色阶段到达，则必须等到下一个绿色阶段开始。 开始穿越后，您总是花费恰好 t 个时间单位沿着那条路行驶。 

任务是计算从节点 1 到节点 n 所需的最短可能时间。 

该图最多有 100,000 个节点和 100,000 条道路。 每个道路查询都需要对与时间相关的行为进行推理，但结构仍然是一个标准的最短路径问题，带有边缘松弛的扭曲。 

一个天真的解释是忽略交通信号灯并将每条边视为成本为 t。 这会立即失败，因为等待时间可以主导答案，并且它们取决于到达时间，而不仅仅是图形结构。 

当强制等待时，即使就纯边缘权重而言存在较短的路径，也会出现微妙的边缘情况。 例如，假设您可以通过与绿色阶段对齐的长路径提前到达节点，或者稍后通过与红色阶段对齐的较短路径到达节点。 贪婪的最短边方法会错误地选择后者。 

另一个常见的失败是假设每个节点仅发生一次等待，而不是每次边缘遍历。 等待取决于每个端点的确切到达时间，因此到达同一节点的两条不同路径可能会产生不同的未来成本。 

## 方法

 蛮力的想法是将其视为与时间相关的图形问题，并模拟遍历它的所有可能的方式。 从（节点，时间）定义的状态开始，我们尝试所有传出边，通过检查交通灯周期计算下一个有效出发时间，然后递归地继续或使用 BFS 随时间变化的状态。 这是正确的，因为它明确地模拟了所有可行的时间表。 

问题是时间是无限的。 即使我们只考虑到达后发生的时间，每次放松都会产生新的不同时间戳。 在最坏的情况下，每次边遍历都可以生成唯一的时间值，并且状态数量随着时间的大小而不是节点的数量而增长。 由于边缘多达 10^5，这会退化为状态爆炸。 

关键的观察结果是，该问题仍然满足最短路径的最优子结构属性：一旦我们确定了节点的最佳已知到达时间，我们就永远不需要以更糟糕的时间重新访问它。 唯一的复杂之处是边缘松弛通过确定性函数取决于到达时间：等待时间是根据时间模 (r + g) 计算的。 这使得该图适合 Dijkstra 算法，其中边权重不是恒定的，但可以动态评估。 

我们不枚举状态，而是维护每个节点的已知到达时间。 当我们在时间 T 放松从 u 到 v 的边时，我们计算循环引起的等待时间，将其添加到 T，然后添加遍历时间 t。 这会产生 v 的候选到达时间，就像加权边缘一样。 

这将问题转换为具有非常量但定义明确的松弛函数的标准单源最短路径计算。

 | Dijkstra 与时间相关的放松 | O((n + m) log n) | O((n + m) log n) | O(n + m) | 已接受 |

 ## 算法演练

 1. 为图构建一个邻接表，其中每条边存储（邻居、行程时间 t、红色 r、绿色 g）。 这允许对每个节点的传出道路进行有效迭代。 
2. 初始化一个大小为 n 且无穷大的数组 dist，除了 dist[1] = 0，因为我们在时间 0 从节点 1 开始。 
3. 使用按当前已知时间排序的优先级队列。 插入 (0, 1) 作为起始状态。 
4. 重复提取已知到达时间cur最小的节点u。 如果 cur 已经大于 dist[u]，请跳过它，因为我们有一个更广为人知的方法来到达 u。 
5. 对于从 u 到 v 的每条边，计算循环长度 c = r + g。 将循环内的位置确定为 cur % c。 
6. 如果该位置位于红色阶段，即小于 r，则将等待时间计算为 r - (cur % c)。 否则等待时间为零。 该模型等待直到绿色阶段开始。 
7. 将候选到达时间计算为 cur + waiting + t。 这代表我们最早可以完成跨越这一边缘的时间。 
8. 如果该候选时间改善了 dist[v]，则更新它并将 (candidate, v) 推入优先级队列。 
9. 继续，直到处理完所有可达节点。 答案是 dist[n]。 

正确性依赖于这样一个事实：一旦一个节点以最短的时间从优先级队列中弹出，以后的松弛就不能为其产生更好的到达时间。 尽管边权重取决于时间，但松弛函数是确定性的和单调的，因为较晚的到达不能在同一边上产生较早的离开。 

## 为什么它有效

 核心不变量是 dist[u] 始终存储迄今为止找到的节点 u 处可实现的最小到达时间，并且优先级队列始终扩展当前最小的此类时间。 等待时间函数将每次遍历转换为仅基于到达源节点的时间的确定性成本，因此每次边缘松弛相当于在已知状态上评估固定函数。 由于所有成本都是非负的，并且 Dijkstra 总是按时间递增顺序最终确定节点，因此稍后到达节点的任何替代路径都无法追溯性地改进早期状态，即使对于时间相关的边缘，这也能保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b, t, r, gr = map(int, input().split())
        g[a].append((b, t, r, gr))
        g[b].append((a, t, r, gr))

    INF = 10**30
    dist = [INF] * (n + 1)
    dist[1] = 0

    pq = [(0, 1)]

    while pq:
        cur, u = heapq.heappop(pq)
        if cur != dist[u]:
            continue

        for v, t, r, gr in g[u]:
            cycle = r + gr
            pos = cur % cycle

            wait = 0
            if pos < r:
                wait = r - pos

            nxt = cur + wait + t

            if nxt < dist[v]:
                dist[v] = nxt
                heapq.heappush(pq, (nxt, v))

    print(dist[n])

if __name__ == "__main__":
    solve()
```邻接列表存储完整的边参数，以便每次松弛可以在本地计算等待时间，而无需任何全局预处理。 

优先级队列确保我们始终扩展当前最著名的部分路由。 支票`if cur != dist[u]`避免处理陈旧状态，这对于将每个操作的复杂性保持在对数范围内至关重要。 

等待逻辑是唯一的非标准部分：它将循环约束转换为根据当前时间戳计算的单个附加延迟。

 从节点 1 到节点 2，到达时间处于长度为 1 的红色阶段，因此我们等待 1，然后行进 4。从节点 2 开始，相对于第二个周期，到达时间 5 再次处于红色阶段，迫使在长遍历之前等待 1。 

这证实了最优性取决于到达时间，而不仅仅是路径结构。

 ## 边缘情况

 当 r = 0 时，会出现一种边缘情况，这意味着没有红相。 在这种情况下，等待计算绝不能触发。 对于像这样的输入`1 2 5 0 10`，算法正确计算 pos = 0 并且看不到红色区间，产生直接成本 5。 

另一种情况是到达时间恰好落在红色和绿色之间的边界处。 由于 red 被定义为间隔 [0, r)，因此恰好在 r 时间到达不应导致等待。 模逻辑处理这个问题，因为 pos >= r 进入绿色阶段。 

最后一个微妙的情况是多条路径以不同的时间到达节点。 优先级队列确保首先处理最早到达的数据，并丢弃所有较晚到达的数据。 对于在长时间等待的情况下快速到达和在不等待的情况下缓慢到达的节点，该算法正确地评估两者，但仅保留最小结果时间，因为每个松弛都是独立评估的。
