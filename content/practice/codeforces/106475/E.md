 ## 解决方案
 # 问题理解

 我们有一个无限的网格。 有些单元格已经包含标记。 当前棋盘保证避开水平、垂直或对角线上的任何三个连续标记单元。 

我们需要计算有多少个空单元格可以接受一个额外的标记，以便在放置它后，至少存在一行三个连续标记的单元格。 

输入给出所有当前标记的单元格的坐标。 输出是可以完成长度为 3 的线的不同空坐标的数量。 

重要的限制是现有标记最多可以有 200,000 个，而坐标的绝对值可以大到 10^9。 扫描棋盘的解决方案是不可能的，因为棋盘实际上是无限的。 即使检查大边界矩形中的每个坐标也需要远远超过可用时间。 我们需要一种算法，其工作取决于标记的数量，而不是坐标范围。 

现有三元组的缺失是一个有用的保证。 这意味着每一个有效的动作都是从两个现有标记和一个新标记创建的。 我们永远不需要处理棋盘已经包含获胜线的情况。 

一个常见的错误是计算可能的对而不是可能的单元格。 不同的对可能会建议相同的空单元格，因此我们必须删除重复项。 

例如，考虑：```
3
0 0
1 0
0 1
```正确答案是`4`。 细胞`(2,0)`,`(-1,0)`,`(0,2)`， 和`(0,-1)`所有这些都创建了水平或垂直的三重。 单独计算每对完成情况的粗心方法可能会多次计算同一位置。 

另一种边缘情况是两个标记对角线但不够接近：```
2
0 0
1 2
```正确答案是`0`。 这两个标记不属于任何可能缺少一个单元格的长度为三的行。 仅检查两个标记是否存在而不验证距离会产生错误的答案。 

# 方法

 直接的方法是检查每个空单元格并测试在那里做标记是否会创建一个三元组。 这是正确的，因为每个可能的答案都会被检查。 问题在于空单元格的数量没有任何有意义的限制。 坐标最大为 10^9，因此即使少量标记也可以拥有巨大的周围区域。 暴力法甚至无法枚举候选者。 

关键的观察结果是，每次成功的移动都必须完成恰好由三个单元格组成的部分。 这样的线段只有四种可能的方向：水平、垂直和两条对角线。 如果我们知道一个现有标记，我们只需要朝这些方向看一两个单元格的距离即可。 

对于固定方向向量`(dx, dy)`，两个现有标记可以出现在长度为三的线段的三个可能位置。 如果第一和第二个单元被占用，则缺失的单元是该对之前的一步和该对之后的一步。 如果第一个和第三个单元格被占用，则缺少的单元格是中间的单元格。 由于只有四个方向和恒定的距离检查，因此每个现有标记仅生成恒定数量的候选者。 

最后一步是重复数据删除。 我们将每个可能的答案坐标插入到一个集合中。 已经被占用的坐标将被忽略，因为我们必须在空单元格中放置一个标记。

 | --- | --- | --- | --- |
 | 蛮力 | O(搜索板面积) | O(搜索板面积) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 # 算法演练

 1. 将所有现有的标记单元存储在哈希集中。 坐标查找必须是恒定时间，因为每个生成的候选者都需要根据当前板进行检查。 
2. 对于每个标记的单元格，检查四个方向`(1,0)`,`(0,1)`,`(1,1)`， 和`(1,-1)`。 这些代表了三细胞系的所有可能的方向，没有重复。 
3. 对于每个方向，检查一步之外的单元格。 如果被占用，则这两个单元格可以是三元组的前两个位置。 添加两个可能缺失的单元格，一个在该对之前，一个在该对之后。 
4. 对于同一方向，检查两步外的单元格。 如果被占用，则两个标记可以是三元组的端点。 添加中间的单元格作为可能的答案。 
5. 删除已被占用的候选项。 唯一坐标的剩余数量就是答案。 

为什么有效：每个有效的移动都会创建一行三个单元格。 在该行中，选取两个已占用的单元格中的任意一个，并考虑朝向另一个已占用的单元格的方向。 两个现有单元格之间的距离为一或二。 该算法精确检查这两种情况并添加缺失的位置。 由于每个生成的位置都存储在一个集合中，因此发现同一动作的多种方式不会影响结果。 

# Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    n = int(input())
    points = set()

    for _ in range(n):
        x, y = map(int, input().split())
        points.add((x, y))

    directions = [
        (1, 0),
        (0, 1),
        (1, 1),
        (1, -1),
    ]

    ans = set()

    for x, y in points:
        for dx, dy in directions:
            x1, y1 = x + dx, y + dy
            if (x1, y1) in points:
                a = (x - dx, y - dy)
                b = (x + 2 * dx, y + 2 * dy)
                if a not in points:
                    ans.add(a)
                if b not in points:
                    ans.add(b)

            x2, y2 = x + 2 * dx, y + 2 * dy
            if (x2, y2) in points:
                mid = (x + dx, y + dy)
                if mid not in points:
                    ans.add(mid)

    print(len(ans))

if __name__ == "__main__":
    solve()
```代码的第一部分构建占用单元的集合。 Python 元组用作坐标表示，允许直接进行成员资格检查。 

方向列表仅包含四个向量，因为相反的方向将描述同一条线。 例如，检查`(1,0)`已经涵盖了水平三元组，所以检查`(-1,0)`只会重复工作。 

第一个条件检查相邻的标记单元格。 如果`(x,y)`和`(x+dx,y+dy)`被占用时，它们形成三元组的两个相邻单元。 第三个单元格可以位于它们的任一侧。 

第二个条件检查由一个间隙分隔的单元格。 如果`(x,y)`和`(x+2dx,y+2dy)`被占用，唯一可能缺失的位置是它们的中间单元格。 

套装`ans`是必要的，因为可以从不同的现有标记或不同的方向生成相同的空单元。 Python整数直接处理大坐标值，因此不需要溢出处理。 

# 工作示例

 使用第一个示例：```
4
2 2
3 3
4 2
5 2
```该算法根据四个方向检查每个标记。 

| 当前单元格| 方向 | 发现细胞 | 添加候选人 |
 | --- | --- | --- | --- |
 | (2,2) | (1,1) | (3,3) 存在 | (1,1), (4,4) | (1,1), (4,4) |
 | (4,2) | (1,0)| (5,2) 存在 | (3,2), (6,2) | (3,2), (6,2) |
 | (4,2) | (1,-1) | (1,-1) | (3,3) 存在于距离 1 | (5,1), (2,4) | (5,1), (2,4) |

 经过所有检查后，所有六个生成的位置都是不同的，因此答案是：```
6
```这说明了为什么我们必须考虑相邻对的两侧。 一对可以创造出两种不同的获胜动作。 

对于第二个样本：```

        for _ in range(n):

                        ans.add(p)

        return str(len(ans))

    sys.stdin = old_stdin
    return result

 # 边缘情况

 对于重复计数的情况：```
3
0 0
1 0
0 1
```这对`(0,0)`和`(1,0)`建议`(2,0)`和`(-1,0)`。 这对`(0,0)`和`(0,1)`建议`(0,2)`和`(0,-1)`。 最终集合包含四个单元格，所以答案是`4`。 如果在没有一组的情况下计算候选者，重叠的发现可能会夸大答案。 

对于对角间隙：```
2
0 0
2 2
```这两个标记在对角线上正好相距两步。 该算法检测到`(1,1)`由于缺少中间单元格，所以答案是`1`。 

对于远处的对角线单元格：```
2
0 0
1 2
```没有检查的偏移与有效方向上的距离一或距离二匹配。 候选集保持为空，给出答案`0`。 

对于接近整数限制的坐标：```
2
1000000000 1000000000
999999999 999999999
```该算法仍然有效，因为坐标最多仅移动两个单位。 Python 整数安全地表示这些值，并且集合操作的行为与小坐标相同。
