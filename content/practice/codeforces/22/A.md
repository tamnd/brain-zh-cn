 ## 解决方案
 ## 问题理解

 给定一个小的整数数组，需要找到严格大于数组中最小元素的最小值。 

另一种思考方式是：如果我们删除重复的值，对剩余的数字进行排序，然后查看第二个元素，该值就是答案。 如果这样的值不存在，我们打印`NO`。 

例如，在数组中：```
1 2 2 -4
```最小值是`-4`。 最小的数大于`-4`是`1`，所以答案是`1`。 

限制很小。 数组长度最多为 100，因此即使是二次解也是完全安全的。 一个`O(n^2)`算法最多会执行 10,000 次比较，这对于 2 秒的时间限制来说可以忽略不计。 内存使用量在这里也无关紧要，因为输入非常小。 

棘手的部分不是性能，而是正确处理重复项。 该问题要求严格大于最小值的最小数字，而不是对整个数组进行排序后的第二个元素。 

考虑这个输入：```
5
1 1 1 2 3
```正确答案是：```
2
```如果我们简单地对数组进行排序并取出索引 1 处的元素，我们会得到`1`，这是错误的，因为最小值的重复项不计算在内。 

当所有值都相等时，会发生另一个重要的边缘情况：```
4
7 7 7 7
```没有大于最小值的数字，因此正确的输出是：```
NO
```粗心的实现可能在删除重复项并崩溃后仍尝试访问第二个元素，或者错误地打印`7`。 

负值也很重要：```
5
-10 -5 -10 -3
```最小值是`-10`，以及比它大的最小值`-5`。 对于负数，排序逻辑也必须正确工作。 

## 方法

 最直接的蛮力想法是将每个元素与其他元素进行比较。 我们可以先找到最小值，然后再次扫描数组并搜索大于该最小值的最小数。 这已经在线性时间内起作用了。 

更字面的暴力版本会生成所有不同的值，对它们进行排序，然后取第二个值。 由于数组最多包含 100 个元素，因此即使排序也完全没问题。 对 100 个数字进行排序的成本大约为`100 log 100`，很小。 

这个问题有趣的部分是理解“二阶统计量”在这里的真正含义。 它并不意味着已排序的原始数组中的第二个位置。 它表示排序后的第二个不同值。 

这一观察立即提出了一个干净的解决方案：

 1. 删除重复项。 
2. 对剩余值进行排序。 
3. 如果存在的不同值少于两个，则打印`NO`。 
4. 否则打印第二个值。 

蛮力之所以有效，是因为输入很小，但不同值观察使实现更加干净且不易出错。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 已接受 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.读取整数`n`和数组值。 
2. 将数组转换为集合以去除重复项。 

此步骤至关重要，因为最小值的重复出现不应影响答案。 
3. 将集合转换回列表并按升序对其进行排序。 

排序后，第一个元素是最小的不同值，第二个元素（如果存在）就是我们需要的答案。 
4. 检查存在多少个不同的值。 

如果大小小于 2，则没有有效的二阶统计量。 
5. 如果至少有两个不同的值，则打印索引处的元素`1`。 

由于数组已排序，因此这是严格大于最小值的最小值。 

### 为什么它有效

 删除重复项后，每个剩余的数字都代表与原始数组不同的一个值。 对这些值进行排序会将它们按升序排列。 第一个值是最小的不同元素，下一个值恰好是比它大的最小不同元素。 由于问题定义直接匹配此属性，因此算法始终会产生正确的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
arr = list(map(int, input().split()))

distinct = sorted(set(arr))

if len(distinct) < 2:
    print("NO")
else:
    print(distinct[1])
```该解决方案首先通常使用快速输入读取数组。 对于这些限制来说，快速 I/O 实际上并不是必需的，但它是竞争性编程中的标准做法。 

关键行是：```
distinct = sorted(set(arr))
```这`set`自动删除重复值。 这可以防止重复的最小值错误地成为答案。 在那之后，`sorted`按升序排列剩余的数字。 

长度检查很重要，因为数组如下：```
5 5 5 5
```重复删除后仅产生一个不同的值。 访问索引`1`不检查会导致错误。 

最后，如果至少存在两个不同的值，则第二小的不同数字恰好是`distinct[1]`。

 最小不同值是`-4`。 下一个较大的不同值是`1`，它符合所需的定义。

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    arr = list(map(int, input().split()))

    distinct = sorted(set(arr))

    if len(distinct) < 2:
        print("NO")
    else:
        print(distinct[1])

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output.strip()

# provided sample
assert run("4\n1 2 2 -4\n") == "1", "sample 1"

# minimum size input
assert run("1\n5\n") == "NO", "single element"

# all values equal
assert run("5\n7 7 7 7 7\n") == "NO", "all equal"

# negative numbers
assert run("5\n-10 -5 -10 -3 -5\n") == "-5", "negative values"

# already sorted distinct values
assert run("4\n1 2 3 4\n") == "2", "simple increasing"

# duplicates of minimum
assert run("6\n1 1 1 2 3 4\n") == "2", "duplicate minimum"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`1 / 5`|`NO`| 最小可能的数组大小 |
 |`5 / 7 7 7 7 7`|`NO`| 所有值均相同 |
 |`5 / -10 -5 -10 -3 -5`|`-5`| 负数的正确处理 |
 |`4 / 1 2 3 4`|`2`| 基本的明显增加案例 |
 |`6 / 1 1 1 2 3 4`|`2`| 忽略最小值的重复项 |

 ## 边缘情况

 考虑所有值都相等的情况：```
4
7 7 7 7
```该算法将数组转换为集合：```
{7}
```排序后：```
[7]
```不同值的数量只有 1，因此算法输出：```
NO
```这是正确的，因为没有任何值严格大于最小值。 

现在考虑重复的最小值：```
6
1 1 1 2 3 4
```最小值出现多次。 重复删除后：```
{1, 2, 3, 4}
```排序给出：```
[1, 2, 3, 4]
```算法输出`2`，这是严格大于的最小值`1`。 简单地对原始数组进行排序并获取第二个元素的简单方法将错误地返回`1`。 

最后，考虑负数：```
5
-10 -5 -10 -3
```删除重复项并排序后：```
[-10, -5, -3]
```第二个不同的值是`-5`。 该算法可以正常工作，因为整数排序自然可以处理负值。
