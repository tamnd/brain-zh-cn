 ## 解决方案
 ## 问题理解

 办公楼层表示为`n × m`网格。 每个单元格要么是空闲的，写为`0`，或被家具挡住，写为`1`。 We want to place one rectangular table whose sides stay aligned with the grid. 矩形覆盖的每个单元格都必须是空闲的。 

目标不是最大化面积。 We want the rectangle with the largest perimeter. 对于有高度的矩形`h`和宽度`w`，周长为：$$2(h + w)$$输出是所有有效矩形中可能的最大周长。 

这些约束足够小，以至于几种方法都是可行的，但仍然足够大，足以惩罚粗心的暴力行为。 既然两者`n`和`m`至多是`25`，网格最多包含`625`细胞。 枚举所有可能的矩形大约需要：$$25^2 \times 25^2 = 390625$$候选矩形，这是可以管理的。 当我们还扫描每个矩形内的每个单元格以验证它仅包含零时，就会出现问题。 在最坏的情况下，每个矩形最多可以包含`625`细胞，大致导致：$$390625 \times 625 \approx 2.4 \times 10^8$$操作，这在 Python 中是不必要的繁重操作。 

一些边缘情况很容易被错误处理。 

单个空闲单元仍应产生有效答案。 例如：```
1 1
0
```唯一有尺寸的矩形`1 × 1`，所以周长是`4`。 

粗心的实现可能会错误地返回`0`因为它假设矩形的宽度和高度必须超过一个单元格。 

另一个棘手的情况是当存在空闲单元但无法形成更大的矩形时：```
2 2
01
11
```答案依然是`4`，因为左上角的单元格单独形成一个有效的表格。 

接触网格边界的矩形通常也会导致差一错误。 考虑：```
2 3
000
000
```最佳矩形跨越整个网格，周长为：$$2(2 + 3) = 10$$使用前缀和或边界数组的实现经常会意外地排除最后一行或最后一列。 

一种更微妙的情况是，一个大矩形恰好包含一个被阻止的单元格：```
3 3
000
010
000
```由于中心障碍物，整个网格无效。 最好的有效矩形是任意`2 × 2`长方形，有周长`8`。 仅检查边界而不是整个内部的算法将错误地返回`12`。 

## 方法

 最直接的解决方案是枚举每个可能的矩形。 矩形由其顶行、底行、左列和右列确定。 对于每个候选者，我们扫描其中的所有单元格并验证每个单元格都是空闲的。 

这种暴力方法是正确的，因为每个有效的矩形都被显式检查。 不会遗漏任何内容，并且每当出现有效矩形时都会更新最佳周长。 

瓶颈来自于重复扫描。 有大约`O(n^2 m^2)`矩形，验证一个矩形可能会花费`O(nm)`时间。 完整的复杂性变为：$$O(n^3 m^3)$$对于最大的网格来说，这会达到数亿次操作。 

关键的观察是矩形验证是昂贵的部分，而不是矩形枚举本身。 如果我们可以在恒定时间内测试一个矩形是否包含任何阻塞的单元格，那么解决方案将立即变得足够快。 

这正是二维前缀和所提供的。 

我们建立一个矩阵，其中每个单元格存储子矩形中出现的块单元格数量`(0,0)`到`(i,j)`。 完成此预处理后，可以查询任意矩形内的阻塞单元格数量`O(1)`使用包含-排除的时间。 

现在算法变成：

 1. 枚举所有矩形。 
2. 查询其中包含多少个被阻止的单元格。 
3. 如果计数为零，则用矩形周长更新答案。 

枚举仍然需要花费`O(n^2 m^2)`，但矩形验证变为恒定时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n立方米) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n²m²) | O(纳米) | 已接受 |

 ## 算法演练

 1. 读取网格并将其转换为数字矩阵，其中空闲单元变为`0`阻塞的细胞变成`1`。 

我们只关心单元格是否遮挡矩形，因此存储整数可以简化后续计算。 
2. 构建二维前缀和数组。 

让`pref[i][j]`表示矩形内被阻挡的单元格数量`(1,1)`到`(i,j)`使用从 1 开始的索引。 

过渡是：$$pref[i][j] = pref[i-1][j] + pref[i][j-1] - pref[i-1][j-1] + grid[i][j]$$这允许在恒定时间内进行任何子矩形求和查询。 
3. 枚举所有可能的顶行和底行。 

每个矩形必须首先选择其垂直边界。 
4. 对于每对行，枚举所有可能的左列和右列。 

至此，一个精确的矩形就固定下来了。 
5. 使用前缀和查询矩形内被阻挡的单元格的数量。 

对于矩形`(r1,c1)`到`(r2,c2)`:$$blocked = pref[r2][c2] - pref[r1-1][c2] - pref[r2][c1-1] + pref[r1-1][c1-1]$$6. 如果矩形包含零个阻挡单元，则计算其周长。 

尺寸为：$$h = r2 - r1 + 1$$

$$w = c2 - c1 + 1$$所以周长是：$$2(h+w)$$7. 跟踪所有有效矩形的最大周长。 

### 为什么它有效

 前缀和矩阵保证每个矩形查询返回该区域内阻塞单元的准确数量。 当且仅当该值等于零时，矩形才有效。 

由于该算法仅枚举每个可能的矩形一次，因此会考虑每个有效的表放置。 答案将使用所有有效矩形中最大的周长进行更新，因此最终结果必须是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    pref = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        for j in range(1, m + 1):
            val = 1 if grid[i - 1][j - 1] == '1' else 0

            pref[i][j] = (
                pref[i - 1][j]
                + pref[i][j - 1]
                - pref[i - 1][j - 1]
                + val
            )

    ans = 0

    for r1 in range(1, n + 1):
        for r2 in range(r1, n + 1):
            for c1 in range(1, m + 1):
                for c2 in range(c1, m + 1):

                    blocked = (
                        pref[r2][c2]
                        - pref[r1 - 1][c2]
                        - pref[r2][c1 - 1]
                        + pref[r1 - 1][c1 - 1]
                    )

                    if blocked == 0:
                        h = r2 - r1 + 1
                        w = c2 - c1 + 1
                        ans = max(ans, 2 * (h + w))

    print(ans)

solve()
```第一部分读取网格并构造前缀和矩阵。 使用从 1 开始的索引`pref`删除几乎所有边界特殊情况。 如果没有这个技巧，触及顶部或左侧边界的查询将需要条件逻辑。 

矩形枚举使用四个嵌套循环。 由于约束条件只有`25 × 25`，这是完全安全的。 昂贵的部分不是枚举本身，而是有效地验证矩形。 

包含排除公式是实现中最微妙的部分。 减法顺序很重要：```
A - B - C + D
```在哪里`D`恢复减去两次的重叠。 

高度和宽度计算均使用`+1`因为矩形边界是包容性的。 忘记这一点会导致单行或单列矩形的周长不正确。 

答案开始于`0`，但问题保证至少有一个空闲单元，因此总是存在一些有效的矩形，并且最终答案至少是`4`。
