 ## 解决方案
 ## 问题理解

 我们有一棵有根的行星之树。 行星 1 是根，其他每个行星都存储其当前直接主管的索引。 该操作选择一个行星，并通过将其父索引减一，将路径上的每个行星从该行星向上移动一级，更靠近根。 

目标是让每个行星都直接受根控制，这意味着除根之外的每个父值都必须变为 1。任务是找到可以实现此目的的最少操作数。 

输入描述了许多独立的树。 对于每棵树，父数组定义层次结构。 每棵树的输出是一个数字：所有操作中选择的行星的最小数量。 

重要的限制是所有测试用例中的行星总数最多为$2 \cdot 10^5$。 这排除了每个测试用例的任何二次方，因为链形树可能已经有 200000 个节点。 我们需要一个接近线性时间的解决方案，其中每个行星都被处理恒定的次数。 

一个常见的错误是贪婪地重复选择最深的行星。 这可以适用于小例子，但它隐藏了实际的结构。 另一个错误是只计算行星距离根部有多少层。 该操作更改父值，而不是深度，因此这两个量不可互换。 

考虑这棵树：```
4
1 2 1
```父母是$p_2=1,p_3=2,p_4=1$。 只有行星 3 需要减一，因此选择行星 3 的一次操作就足够了。 基于深度的方法可能会错误地认为行星 2 也需要工作，因为它位于根部下方。 

另一种情况是：```
4
1 2 3
```这是一条链条。 所需的减量为$0,1,2$对于行星 2、3 和 4。选择行星 4 两次可以解决所有问题，因此答案是 2。每次更改一个边缘的粗心模拟可能会在中间行星上执行不必要的操作。 

## 方法

 思考该过程的直接方法是模拟递减。 每个操作都会影响整个祖先链，因此暴力解决方案可以重复选择一个其父级仍然大于 1 的行星，并在减少父级的同时向根走去。 这是正确的，因为每个操作都与允许的移动完全匹配。 

问题在于重复更改的次数。 在一条长度的链条中$n$，最后一个星球上的一次操作几乎改变了整棵树。 如果我们模拟每个受影响的节点，总工作量可以达到$O(n^2)$，这对于$n=2 \cdot 10^5$。 

关键的观察是停止考虑单独的操作，而是计算每个行星必须执行多少次操作。 让$x_u$是我们选择行星的次数$u$。 每个操作都从行星的子树内部开始$v$减少$p_v$乘以一，因为$v$位于所选行星的根路径上。 

因此对于每个非根行星：$$\sum_{u \in subtree(v)} x_u = p_v - 1$$因为父值必须从$p_v$至 1。 

该方程可以从叶子向上求解。 必须发生的工作量$v$是其子级已经贡献其操作后剩下的内容。 

对于一个星球$v$:$$x_v = (p_v - 1) - \sum_{c \text{ child of } v}(p_c - 1)$$该树保证这些值是非负的。 最终答案就是所有答案的总和$x_v$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 从父数组中为每个行星构建子列表。 树的顺序已经是从较小的索引到较大的索引，但解决方案需要从叶子向上处理节点。 
2. 以相反的顺序遍历树。 对于每个非根行星，从它需要的减量数开始，即$p_v-1$。 
3. 减去所有子项已经提供的所需减量。 这些子操作也发生在子树内$v$，所以它们已经帮助减少$p_v$。 
4.剩下的值就是我们必须选择的次数$v$本身。 将其添加到答案中。 
5. 继续，直到处理完所有非根行星。 

为什么它有效：

 不变的是，在处理一个节点之后，我们已经决定了必须在其子树中开始的操作的确切数量。 节点只关心其子树内部的操作，因为只有那些路径经过它。 当我们计算时$x_v$，我们删除所有子子树的贡献，只留下必须从$v$。 由于每个所需的父减量都被计算一次，因此总和给出了最少的操作数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans_out = []

    for _ in range(t):
        n = int(input())
        p = [0] + list(map(int, input().split()))

        children = [[] for _ in range(n + 1)]
        need = [0] * (n + 1)

        for i in range(2, n + 1):
            children[p[i]].append(i)
            need[i] = p[i] - 1

        order = [1]
        for u in order:
            for v in children[u]:
                order.append(v)

        ans = 0

        for u in reversed(order[1:]):
            cur = need[u]
            for v in children[u]:
                cur -= need[v]
            need[u] = cur
            ans += cur

        ans_out.append(str(ans))

    sys.stdout.write("\n".join(ans_out))

if __name__ == "__main__":
    solve()
```父数组被转换为子列表，以便可以自下而上地处理树。 这`need`数组最初存储每个行星的父行星必须减少的次数。 

遍历顺序从根开始创建，然后反转。 因为在原始遍历中每个父级都出现在其子级之前，所以反转它可以保证子级在其父级之前得到处理。 

更新循环从当前节点中减去子节点的贡献。 这与推导中的方程相同，结果值是必须恰好从该节点开始的操作数。 

不使用递归，这避免了Python在200000个行星链上的递归深度问题。

 ## 边缘情况

 对于最小的树：```
2
1
```行星 2 已经向行星 1 报告。其所需的减少量为$1-1=0$，因此该算法计算零运算。 

对于明星来说：```
5
1 1 1 1
```每个非根行星都已经有父行星 1。全部`need`值为零，因此每个节点贡献零操作。 

对于链条：```
6
1 2 3 4 5
```最后一个行星需要四次减少。 重复选择是最优策略，自下而上的计算将所有需要的工作分配给最深的节点，产生最小的总数。 

对于分支树：```
7
1 1 2 2 3 3
```叶子为父母提供了所需的减少量。 在父级之前处理子级可以防止重复计算，因为每个操作都在其开始的确切节点进行计数。
