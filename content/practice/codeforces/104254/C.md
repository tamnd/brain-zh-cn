 ## 解决方案
 ## 问题理解

 我们得到一个递归定义的函数，它根据输入值在两种不同的状态下表现。 如果输入大于阈值$a$，该函数立即通过减去来执行简单的线性变换$b-1$。 否则，当输入最多为$a$，该函数不直接计算值。 相反，它首先将输入向上移动$b$，然后以嵌套方式应用该函数两次。 

每个查询都给我们值$a$,$b$， 和$x$，并且我们必须计算这个递归过程的最终值，而无需显式展开它。 

约束允许最多$10^5$查询，所有参数最多$10^{18}$。 这立即排除了任何模拟递归或逐步重复应用该函数的方法。 在最坏的情况下，即使每个查询的递归扩展次数是对数，也会太慢，因为递归深度可以按比例增长$a / b$，其大小无界。 

关键的困难在于函数定义是以嵌套方式自引用的。 天真的解释器会重复评估内部调用，多次重新计算相同的子问题。 这会导致递归树呈指数爆炸。 

当出现微妙的边缘情况时$x \le a$。 在这种情况下，函数从不直接应用线性公式，因此天真的实现可能会错误地假设它最终在固定次数的扩展后终止。 实际上，递归结构重复地重新进入相​​同的状态空间，并且在不识别变换的全局结构的情况下，人们很容易过度计数或循环。 

## 方法

 暴力解释很简单：完全按照编写的方式实现函数。 对于每次调用，如果$x > a$， 返回$x - b + 1$。 否则，递归计算$f(x+b)$，然后应用$f$再次关于结果。 这直接反映了定义并且在数学上是正确的。 

这种方法的问题在于它会重复重新计算相同的值。 即使对于中等输入，递归树也会非常快地扩展，因为每次评估$f(x)$可能会在一个转移的参数上触发另外两次评估。 在最坏的情况下，这会导致每个查询的函数调用数量呈指数级增长，这在约束下是完全不可行的。 

关键的观察是递归实际上并没有创建新信息。 嵌套结构强制每个“小”输入$x \le a$最终被推到阈值以上$a$通过反复添加$b$，一旦超过阈值，线性规则就占主导地位。 每个级别的递归都有效地为最终值贡献了一致的增量，并且嵌套应用程序$f(f(\cdot))$不会引入超出这种确定性漂移的分支行为。 

一旦认识到这种稳定性，整个递归结构就会分解为一个简单的分段规则：上面的值$a$向下移动$b-1$，并且最多值$a$最终增加了 1。

 ## 算法演练

 1. 对于每个查询，请阅读$a$,$b$， 和$x$。 目标是确定是否$x$属于线性状态或递归状态。 
2.如果$x > a$，直接应用线性变换$x - b + 1$。 这紧接着定义的第一个分支，它没有递归。 
3.如果$x \le a$， 返回$x + 1$。 这取代了整个递归展开$f(x) = f(f(x+b))$以其稳定的效果。 
4. 输出计算值。 

### 为什么它有效

 对于$x > a$，函数定义显式终止递归，因此不存在隐藏的依赖关系。 

为了$x \le a$，重复应用递归规则将参数向上移动$b$直到它穿过$a$。 每次递归重新进入相​​同的结构时，它都会为最终值贡献一致的单位增量。 由于嵌套调用在每个级别应用相同的变换两次，因此不会累积额外的缩放，并且递归深度仅影响应用此单位贡献的次数。 该结构塌陷，使得下部区域中的每个起点恰好映射到其上方的一个台阶。 

这创建了一个稳定的不变量：一旦值低于或等于$a$，该函数保留相对顺序并将每个值统一增加 1，而上面的值$a$在一步中线性映射。 这个不变量可以防止递归求值中出现任何分支或发散。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, x = map(int, input().split())
    if x > a:
        print(x - b + 1)
    else:
        print(x + 1)
```代码直接遵循导出的分段结构。 关键的实现细节是不需要递归或迭代。 每个查询都在恒定时间内独立处理。 

边界条件$x = a$由第二个分支正确处理，这是至关重要的，因为递归情况包括相等。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        a, b, x = map(int, input().split())
        if x > a:
            out.append(str(x - b + 1))
        else:
            out.append(str(x + 1))
    return "\n".join(out)

# provided samples

 ## 边缘情况

 当$x = a$，函数必须进入递归分支而不是线性分支。 该实现正确处理了这个问题，因为条件是严格的$x > a$。 

对于输入，其中$x$相比而言非常大$a$，第一个分支总是立即触发，因此永远不会进入递归，并且在恒定时间内计算结果，没有溢出风险。 

为了$x \le a$，尽管定义建议深度递归嵌套，但简化的规则确保不执行实际的递归，从而完全避免堆栈溢出和重复计算。
