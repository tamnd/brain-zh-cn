 ## 解决方案
 ## 问题理解

 我们得到一个长字符串，其长度恰好是某个数字的九倍$n$。 这意味着该字符串自然可以被视为一个序列$n$连续的块，每个块的长度为 9。 

我们还给出了一个固定的目标词“BSUIROPEN”。 任务是修改字符串中的字符，使该单词作为子字符串出现尽可能多的次数。 每次修改都意味着将原始字符串中的一个字符替换为另一个大写字母，我们希望最大限度地减少需要的替换次数，同时实现目标单词的最大可能出现次数。 

由于目标单词本身的长度为 9，因此它的任何出现都必须恰好占据字符串中 9 个字符的连续段。 因为总长度正好是$9n$，自然结构表明每个 9 字符块都对应于一个潜在的事件。 

约束条件$9n \le 200{,}000$意味着$n \le 22{,}222$。 这个值足够小，以至于对字符串的任何线性扫描都是有效的，但对整个字符串的任何二次扫描都会太慢。 检查每个字符恒定次数的解决方案就足够了。 

如果假设事件可以任意重叠，则幼稚推理的微妙失败案例就会出现。 例如，在如下字符串中：```
BSUIROPENBSUIROPEN
```人们很容易想到移动子字符串或重叠匹配，但是长度约束所施加的结构意味着我们不会通过跨块混合获得任何东西。 另一个潜在的错误是尝试跨块“全局重新排列”字母，这忽略了每次替换仅影响其位置，并且在块之间移动字母没有任何好处。 

## 方法

 暴力方法会尝试考虑在字符串中形成“BSUIROPEN”出现的所有可能方式。 人们可以想象选择$k$子串开始的位置并检查它们是否可以同时有效。 然而，由于每次出现跨越 9 个字符，并且字符串长度为$9n$，在一般子串放置问题中，选择有效起始位置和解决重叠的方法数量会组合增长。 即使我们将自己限制为有效的起始索引，我们最终仍然需要评估许多重叠的配置，这会导致候选者之间重复进行字符比较，并且很容易超出$O(n^2)$或者更糟。 

关键的观察结果是输入的结构消除了字符串不同部分之间的交互。 每个 9 字符块都已与目标长度对齐。 更改一个块中的字符不会影响任何其他块。 因此，问题简化为独立决定如何以最少的编辑将每个块转换为“BSUIROPEN”。 

对于每个块，成本只是该块与目标字符串不同的位置数。 由于每个块必须对应于一次出现（我们无法获得超出$n$），最大化出现次数相当于使所有块都有效，而最小化替换则相当于对这些局部不匹配成本求和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2 \cdot 9)$或者更糟|$O(n)$| 太慢了 |
 | 最佳|$O(9n)$|$O(1)$| 已接受 |

 ## 算法演练

 我们将字符串视为一系列固定大小的段，并计算每个段需要多少次更改。 

## 算法演练

 1. 将目标模式固定为“BSUIROPEN”。 这是我们关心的唯一有效子字符串，因此每个块都会直接与它进行比较。 
2. 将输入字符串分割成长度为 9 的连续块。每个块代表一个潜在的出现位置。 这种对齐是由输入长度的结构强制的。 
3. 对于每个块，将其与目标字符串逐个字符进行比较，并计算不匹配的数量。 每个不匹配对应于将该块转换为目标所需的一次替换操作。 
4. 累积所有块的不匹配计数。 由于区块是独立的，因此这些成本不会相互干扰。 
5. 输出总累加值，该值代表使每个块等于目标字符串所需的最少替换次数，从而最大化出现次数。 

### 为什么它有效

 目标单词的每次出现必须恰好占据 9 个连续位置。 由于字符串长度可以被 9 整除，因此每个位置恰好属于一个候选块。 在一个块中进行的任何更改都不能提高或恶化另一块成为目标子串的能力。 这种独立性保证了单独最小化每个块的更改也最小化了全局更改的总数，并同时产生最大的发生次数，这总是$n$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    target = "BSUIROPEN"
    
    ans = 0
    for i in range(n):
        block = s[i*9:(i+1)*9]
        for j in range(9):
            if block[j] != target[j]:
                ans += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案读取字符串一次并在连续的 9 个字符切片中对其进行处理。 内部比较循环的大小是固定的，因此它贡献了一个常数因子。 唯一的微妙之处是确保正确的切片边界：每个块从索引开始$9i$并结束于$9i + 8$，包含在内。 这里任何相差一的错误都会在块之间混合字符并破坏正确性。

 ## 边缘情况

 一种边缘情况是块已经完全等于目标字。 在这种情况下，失配计数为零并且不需要替换。 例如，输入：```
1
BSUIROPEN
```该算法检查每个字符，没有发现差异，然后输出 0。块的独立性确保这不会影响计算的其他部分。 

另一种边缘情况是根本没有字符与目标匹配。 例如：```
1
AAAAAAAAA
```每个位置恰好不匹配一次，因此算法计算了 9 次替换。 即使每个位置不同，每个字符的比较也能保证正确性。 

最终的结构边缘情况是存在多个相同的块时。 由于每个块都是独立处理的，因此相同的输入块会产生相同的成本，并且总和呈线性缩放，段之间没有任何干扰。
