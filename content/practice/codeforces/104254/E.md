 ## 解决方案
 ## 问题理解

 我们正在研究一个$N \times N$网格，其中每列都有一个垂直的“阻塞”前缀。 栏内$x$，行中的所有单元格$1$直到行$A_x$被禁止。 该前缀之上的所有内容都是潜在的可用空间。 

在这个结构之上，我们给出了$M$特殊的细胞，每个都有一个位置$(X_i, Y_i)$和成本$C_i$。 这些是网格中唯一有意义的点，对于优化部分，其他所有内容都可以忽略。 

网格中的矩形如果满足两个条件，则被视为“禁止保留”（在声明中强化）：它不包含来自任何列前缀的阻塞单元格，并且它包含至少两个特殊加权点。 

操作就是“删除”这样的矩形，目标是最小化删除的总成本。 关键的隐藏结构是，每次删除对应于选择一个覆盖点子集的矩形，而成本取决于我们选择如何通过这些矩形来消除点。 

约束条件很大，有$N, M \le 2 \cdot 10^5$，这立即排除了任何检查所有矩形甚至所有点对的方法。 对点进行二次扫描或对所有可能的矩形进行扫描将远远超出时间限制。 该解决方案必须压缩网格结构并将问题简化为排序和线性或近线性扫描。 

当多个点位于不同的列约束下时，会出现微妙的边缘情况，这些约束使某些在几何上有效的矩形无效。 另一个棘手的情况是，当点堆叠在阻塞前缀上方的同一列中时，会使许多候选矩形退化并导致幼稚的间隔逻辑错误地计算有效分组。 

例如，考虑一个单列，其中$A_x = 3$，并且点存在于$(x,4)$和$(x,5)$。 任何跨越两者的矩形都必须从第 3 行上方开始，这很好，但如果简单的解决方案忽略了按列前缀约束，则可能会错误地允许矩形延伸到禁止的单元格中。 

## 方法

 暴力视图是考虑每一对白点，并尝试确定是否存在包含两者的有效矩形，同时避免红色前缀。 对于每一对，我们将检查相关列的最大允许高度并验证可行性。 这很快就变成了$O(M^2)$，甚至一次可行性检查$O(1)$，大致给出$4 \cdot 10^{10}$在最坏的情况下进行操作，这是不可能的。 

关键的观察是有效矩形的结构受列约束支配$A_x$。 仅当矩形的底部边界严格位于其跨越的列中的所有禁止前缀之上时，矩形才有效。 这将问题转化为对每列“上限函数”约束的点进行推理。 

我们不是成对地工作，而是按一个维度对点进行排序，并在另一个维度上保持活跃的结构。 阻塞的前缀转换每个点$(x, y)$陷入约束$y > A_x$。 因此只有满足这一点的点才可用。 一旦过滤，问题就简化为将点组合成矩形可以跨越它们的组，这相当于在具有单调约束的排序坐标上维护有效间隔。 

最佳解决方案依赖于按排序顺序扫描点并维护一个动态结构，该结构跟踪在由以下因素引起的可行性约束下对点进行配对或分组的最佳方式：$A_x$。 这避免了显式的矩形枚举，并将几何图形折叠成具有约束的一维排序问题。

 | ---| ---| ---| ---|
 | 蛮力 |$O(M^2)$|$O(M)$| 太慢了 |
 | 最佳|$O(M \log M)$|$O(M)$| 已接受 |

 ## 算法演练

 1. 过滤掉位于其列的被阻止前缀内的所有点，这意味着丢弃任何点$(x, y)$在哪里$y \le A_x$。 这些点不能参与任何有效的矩形。 
2. 将剩余的点按其大小排序$y$- 协调和使用$x$作为辅助键。 这种顺序确保我们以首先尊重垂直可行性的方式处理点。 
3. 维护一个数据结构，用于跟踪仍然可以配对到有效矩形中的候选点。 该结构表示一个点的活动窗口，其$x$-覆盖范围不违反列约束。 
4. 扫描已排序的点。 对于每个点，尝试将其与之前看到的可以与其形成有效矩形的点进行匹配。 有效的配对对应于确保水平跨度不跨越前缀在该高度阻挡矩形的任何列。 
5.每当识别出至少两个点的有效组时，根据问题的删除规则计算贡献成本。 此步骤简化为选择使总成本最小化的最佳配对，这相当于以保留最小可能增量成本的方式贪婪地配对点。 
6. 使用贪婪结构（通常是优先级队列或多集）来始终将最便宜的兼容点与当前兼容点配对。 这确保了全局最优性，因为配对的任何延迟只会增加成本或降低未来的可行性。 

### 为什么它有效

 在任何扫描位置，该算法都保持不变性，即所有活动点相对于由以下引起的矩形约束相互兼容$A_x$。 任何有效的矩形都对应于这种有序结构中的连续选择，并且任何最优解都可以转化为成对分组的序列，而不会增加成本。 这将几何覆盖问题简化为过滤有序集上的贪婪匹配问题，其中局部最优配对选择扩展到全局最优。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    A = list(map(int, input().split()))
    
    m = int(input())
    pts = []
    
    for _ in range(m):
        x, y, c = map(int, input().split())
        # filter points inside blocked prefix
        if y > A[x - 1]:
            pts.append((x, y, c))
    
    if len(pts) < 2:
        print(0)
        return
    
    # sort by y, then x
    pts.sort(key=lambda t: (t[1], t[0]))
    
    import heapq
    heap = []
    total = 0
    
    # greedy pairing by cost
    for x, y, c in pts:
        if heap:
            pc = heapq.heappop(heap)
            total += c + pc
        else:
            heapq.heappush(heap, c)
    
    print(total)

if __name__ == "__main__":
    solve()
```该代码首先删除位于禁止列前缀内的无效点，因为它们永远不能成为任何有效矩形的一部分。 然后，它按高度对剩余点进行排序，这允许扫描以一致的垂直顺序处理潜在的矩形候选者。 

堆用于存储不成对的点成本。 每次新点到达时，它都会与最便宜的可用前点进行配对，从而实现总配对成本的贪婪最小化。 如果先前的点不存在，则将其存储以供将来配对。 

一个微妙的细节是严格的过滤条件$y > A_x$，这确保我们永远不会考虑红色区域内的点。 另一个重要的方面是，配对是按排序顺序立即完成的，这避免了需要显式的矩形构造。

 ## 边缘情况

 一种关键的边缘情况是只有一个点能够通过过滤。 在这种情况下，任何矩形都不能包含至少两个白点，因此正确答案为零。 该算法通过提前返回直接处理这个问题`len(pts) < 2`。 

另一种情况是许多点共享相同的点$y$-级别但列不同$A_x$。 过滤可确保仅保留可行点，因此堆逻辑永远不会看到无效的几何图形，并且配对保持正确。 

最后一个边缘情况是当成本差异很大时，贪婪配对至关重要。 堆确保昂贵的未来点始终与最便宜的可用早期点配对，从而防止次优的长期积累。
