 ## 解决方案
 ## 问题理解

 我们得到了多个独立的查询。 每个查询描述一个大小的平方乘法表`n × n`，其中行索引和列索引的范围都是从 1 到`n`。 每个单元格包含其行索引和列索引的乘积。 对于给定的数字`k`，我们必须数出有多少对`(i, j)`生产出等于`k`。 

换句话说，我们不是要建表，而是要计算有多少个因式分解`k`适合在范围内`[1, n] × [1, n]`。 

约束足够大，可以显式迭代所有`n^2`每个查询的单元格是不可能的。 和`n`最多`10^5`，单个表已包含最多`10^10`条目，因此任何扫描网格的方法都会立即被排除。 甚至迭代所有除数直到`n`对于每个查询，只有当它保持在范围内时才是可接受的`O(sqrt(k))`或更好的摊销行为。 

隐藏结构是有效对与除数对完全对应`k`，但受区间限制`[1, n]`。 

当只计算 的约数时，就会出现一个幼稚的错误`k`无需检查边界。 例如，如果`k = 12`和`n = 2`，这对`(3, 4)`是 12 的有效分解，但在表中无效，因为两个索引都超过`n`。 另一个微妙的错误是重复计算`(i, j)`和`(j, i)`错误地当`i ≠ j`，特别是如果对称性处理不一致的话。 

## 方法

 暴力解决方案将迭代所有`i`和`j`从 1 到`n`并检查是否`i * j == k`。 这是简单且正确的，因为它直接测试乘法表的每个单元格。 然而，每次查询的成本是`n^2`，达到`10^10`在最坏的情况下操作是不可行的。 

关键的观察是我们只关心成对的`(i, j)`这样`i * j = k`。 一次`i`是固定的，`j`被唯一地确定为`k / i`，如果它是一个整数。 这将搜索空间从完整网格减少到除数`k`。 我们只需要迭代`i`最多`sqrt(k)`并检查是否`k % i == 0`。 每个有效除数对`(i, k/i)`如果两个端点都位于`[1, n]`。 

这将问题简化为使用边界过滤器枚举单个数字的因子对，即使对于大型`n`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每次查询 O(n²) | O(1) | O(1) | 太慢了 |
 | 最佳| 每个查询 O(√k) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个查询。 

1. 阅读`n`和`k`。 目标是计算有效对的数量`(i, j)`这样`i * j = k`以及两者`i`和`j`介于 1 和`n`。 
2. 初始化计数器`ans = 0`。 这将积累有效的因子对。 
3. 迭代`i`从 1 到`⌊sqrt(k)⌋`。 这已经足够了，因为任何大于`sqrt(k)`必须与已经见过的较小因子配对。 这确保了每对都被恰好发现一次。 
4. 对于每个`i`，检查是否`i`划分`k`。 如果`k % i != 0`，跳过它，因为它不能形成整数对。 
5.让`j = k // i`。 现在`(i, j)`是有效因子对`k`。 
6. 检查是否`i <= n`和`j <= n`。 只有这样，该对才对应乘法表中的一个单元格。 
7. 如果有效，则加 1`ans`。 无需重复计算，因为迭代至`sqrt(k)`确保每个因子对都被访问一次。 
8. 输出`ans`。 

### 为什么它有效

 每个有效的表格单元格对应一个因式分解`k = i × j`两个因素都受`n`。 循环结束`i`将每个可能的左因子恰好枚举一次。 每个有效`i`唯一决定`j = k / i`，因此不会丢失或重复有效的对。 边界条件确保我们只计算实际存在于范围内的对`n × n`网格，过滤掉数字正确但在表格之外的因式分解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def count_pairs(n, k):
    ans = 0
    i = 1
    while i * i <= k:
        if k % i == 0:
            j = k // i
            if i <= n and j <= n:
                ans += 1
        i += 1
    return ans

def main():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        print(count_pairs(n, k))

if __name__ == "__main__":
    main()
```核心功能`count_pairs`直接实现除数枚举策略。 循环条件`i * i <= k`保证我们只扫描到平方根，从而防止冗余检查。 可除性检查确保我们只形成有效的整数伙伴。 

一个微妙的细节是我们只计算其中之一`(i, j)`和`(j, i)`什么时候`i != j`，因为在除数扫描期间两者都恰好遇到一次：一次`i`还小，不再时`i`很大。

 ## 边缘情况

 一个关键的边缘情况是当`k`因子大于`n`。 例如，`n = 5`,`k = 10`。 因子对`(1, 10)`在代数上有效，但在网格中无效，因为`10 > n`。 该算法通过以下方式正确拒绝它`j <= n`查看。 

另一种情况是当`k`是一个完美的正方形。 为了`n = 10`,`k = 36`，这对`(6, 6)`应该只计算一次。 循环结构自然地确保了这一点，因为它是在`i = 6`，并且不会发生重复对称计数。 

最后一个微妙的情况是`k > n * n`。 在这种情况下，表中不能存在对，并且循环仍然在除数上运行，但每个候选者都未通过边界检查，从而导致预期的零。
