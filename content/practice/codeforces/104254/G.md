 ## 解决方案
 ## 问题理解

 给定一块破碎的木板，其底部边缘固定在 x 轴上，其顶部边缘由严格递增 x 坐标的折线描述。 这意味着形状是 x 单调的：如果从左向右行走，则永远不会在 x 方向上向后移动，并且边界完全由给定的顶点确定。 

木板最初有一些区域，即该破碎顶部边界下方和 x 轴上方的区域。 商人以与其面积成正比的价格购买木板的最终加工版本。 在出售之前，瓦迪姆可以浇注环氧树脂。 环氧树脂有两个作用：它的成​​本与使用量成正比，并且它可以填充间隙，以便在沿着直线最终边界切割木板之前，损坏结构的部分被“平滑”成单一的最终形状（如声明中的后处理步骤所暗示的那样）。 

关键含义是环氧树脂用于在销售前修改有效顶部边界，并且几何形状的任何变化都会改变最终销售面积和消耗的环氧树脂量。 目标是选择要执行的平滑程度，以使利润（定义为最终区域的收入减去环氧树脂成本）最大化。 

输入大小最多为 10^5 个顶点，因此任何几何形状的二次重建或成对结构检查都是不可能的。 该结构在 x 上是单调的，因此解决方案必须在线性或近线性时间内工作，可能使用基于堆栈的几何缩减或凸性属性。 

一种简单的方法可能会尝试模拟“拉直”折线部分的所有可能方式，或者考虑用直线替换所有子线段。 这会立即失败，因为段选择的数量是二次的。 

当局部思考时，会出现一个更微妙的问题。 例如，如果三个连续的点形成像 (1, 4)、(2, 1)、(3, 4) 这样的“凹凸”，则简单的算法可能会假设每个局部平滑都是独立的。 这是错误的，因为删除一个凹面可能会暴露另一个以前不相关的凹面，这意味着该结构是全局的，而不是局部的。 

另一个陷阱是假设原始折线始终是最佳的或始终保持不变。 如果环氧树脂相对于销售价格便宜，那么将边界转变为全局更“凸”的形状可能是有益的，即使局部修改看起来成本高昂。 

## 方法

 蛮力解释是考虑用直线段替换破碎顶部边界部分的所有可能方法。 每个这样的选择都定义了一个不同的最终多边形，其面积可以计算，并且环氧树脂成本对应于原始形状和修改后的形状之间的差异。 然而，选择定义有效上边界的顶点子集的方法数量与点的数量呈指数关系，因为每个顶点都可能根据全局几何形状被删除或保留。 即使仅限于段选择，枚举所有有效的简化也已经增长为 O(n²) 或更糟。 

关键的观察是任何最佳的最终形状必须是给定点的上凸包络。 如果一个点位于其他两点之间的线段下方，则保留它只会减少拉直边界下的最终可实现面积，而不会以取决于局部决策的方式提高利润。 这是一种经典的几何压缩：冗余的“凹”顶点永远不会出现在最佳边界中。 

一旦认识到这一点，问题就简化为构造按 x 坐标排序的一组点的上凸包，这可以使用单调堆栈在线性时间内完成。 在我们获得原始面积和船体面积之后，利润就变成了这两个值的简单线性表达式，因为环氧树脂成本与修改的面积成正比。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解所有边界修改 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 单调凸包+面积计算 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们利用以下事实：多边形是 x 单调的，并且在最佳环氧树脂使用情况下只有上边界发生变化。 

1. 使用连续顶点之间的梯形规则计算给定折线下的原始面积。 每个段根据平均高度乘以宽度贡献一个简单区域。 这给出了基线形状区域。 
2. 使用堆栈按 x 阶递增构造给定点的上凸包。 我们维护一个候选边界，并确保从上方观察时它永远不会出现“凹转”。 如果最后三个点违反凸性，则删除中间的点。 
3. 当我们构建船体时，我们只存储幸存的顶点。 这些代表环氧树脂填充凹形区域后的最终拉直边界。 
4. 以相同的梯形方式计算船体下方的面积，因为船体也是 x 上的分段线性函数。 
5. 将两个领域合并为利润。 如果 m 大于 k，则增加最终面积是有益的，因此我们更喜欢最大化船体面积。 如果 m 小于 k，则环氧树脂产生的任何额外区域都不值得其成本，因此我们实际上保持原始配置。 这导致两个预计算区域之间的简单比较。 

### 为什么它有效

 任何非凸顶点都会严格降低将环氧树脂转化为有利可图的区域的效率，因为它会产生局部凹痕，而这些凹痕始终可以用直段代替，而无需增加环氧树脂与面积的比率。 这产生了一种优势关系，其中凸包边界在边际利润方面永远不会比任何替代边界差。 由于外壳对于 x 排序的点来说是唯一的，因此该算法确定性地产生最佳结构。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def area(poly):
    s = 0.0
    for i in range(len(poly) - 1):
        x1, y1 = poly[i]
        x2, y2 = poly[i + 1]
        s += (y1 + y2) * (x2 - x1) * 0.5
    return s

def cross(o, a, b):
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

n = int(input())
m, k = map(float, input().split())

pts = [tuple(map(int, input().split())) for _ in range(n)]

orig = area(pts)

hull = []
for p in pts:
    while len(hull) >= 2 and cross(hull[-2], hull[-1], p) >= 0:
        hull.pop()
    hull.append(p)

hull_area = area(hull)

if m >= k:
    ans = m * hull_area - k * (hull_area - orig)
else:
    ans = m * orig

print(f"{ans:.6f}")
```该解决方案首先计算原始破碎木板的面积，然后使用单调堆栈构造上凸边界。 叉积条件删除了在形成上包络线时会产生非凸转弯的点。 之后，两个面积都通过梯形计算。 

一个微妙的点是叉积条件的方向。 由于 x 严格递增，因此堆栈维持单个链，并且当转弯不是“上凸”时删除点可确保我们始终保持尽可能高的包络。 

浮点精度就足够了，因为所有计算都是输入坐标的线性组合，并且该问题保证双精度就足够了。 

## 工作示例

 我们追踪一个小型构造示例来说明船体构造和面积比较。 

考虑要点：

 (1, 1), (2, 3), (3, 2), (4, 4)

 我们计算原始面积和船体面积。 

| 步骤| 船体堆栈| 行动|
 | ---| ---| ---|
 | (1,1) | (1,1) | 添加|
 | (2,3) | (1,1),(2,3) | 添加|
 | (3,2) | (1,1),(2,3),(3,2) | 尚未删除 |
 | (3,2) 检查 | (1,1),(3,2) | (1,1),(3,2) | 由于凹性而移除 (2,3) |
 | (4,4) | (1,1),(3,2),(4,4) | 添加|

 中间点 (2,3) 被删除，因为它相对于上包络线创建了一个非凸转弯。 

原始区域使用所有线段，而船体区域使用简化的边界，这增加了最终可实现的形状。 

这表明该算法不是在本地运行，而是全局强制执行信封一致性。 

没有删除任何点的第二个示例：

 (1,1)、(2,2)、(3,3)、(4,4)

 堆栈永远不会弹出，因为这些点已经是凸的。 船体等于原始形状，因此两个区域匹配并且没有环氧树脂引起的变形是有益的。

 ## 边缘情况

 当所有点都位于一条直线上时，就会发生退化情况。 例如，(0,0)、(1,0)、(2,0)。 凸包算法将根据实现保留所有或折叠中间点，但计算的面积始终保持为零。 由于原始面积和船体面积相同，因此利润公式可以正确减少而不会不稳定。 

另一种情况是单个“深谷”，如 (1,5)、(2,1)、(3,5)。 中间点在船体建造期间被移除。 堆栈会弹出 (2,1)，因为它相对于 (1,5) 和 (3,5) 形成凹转。 最终的船体是一个直线段，并且面积差异被正确地捕获为环氧树脂调整的改进。 

最后一个微妙的情况是多个连续点在凸和凹行为之间交替。 堆栈会重复弹出，直到恢复凸性不变量，确保正确解决远程依赖关系，而不是依赖于本地决策。
