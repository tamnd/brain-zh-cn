 ## 解决方案
 ## 问题理解

 我们得到一个包含三个符号的字符串：A、B 和 C。我们必须为每个位置分配一个括号，“(”或“)”，产生相同长度的括号序列。 关键限制是相同的字母必须映射到相同的括号，因此每个 A 都由相同的括号替换，每个 B 由相同的括号替换，每个 C 由相同的括号替换。 

因此，我们不是为每个位置选择括号，而是选择从集合 {A, B, C} 到 {“(”, “)”} 的映射。 只有 8 种可能的映射，但并非所有映射都会产生有效的正则括号序列。 

目标是确定这些映射中的至少一个是否产生正确的括号序列。 

约束 n ≤ 50 非常小。 对所有映射进行暴力破解以及对每个映射进行线性有效性检查很容易足够快，因为我们每个测试用例最多只执行 8 × 50 次操作，且 t ≤ 1000。 

如果试图根据局部平衡或频率贪婪地分配括号而不尊重全局结构，则会出现微妙的失败情况。 例如，假设多数字母应变为“(”可能会失败，因为平衡取决于排序，而不是计数。

 另一个陷阱是将问题视为每个位置独立的问题。 由于所有出现的字母都捆绑在一起，因此不可能翻转单个位置，这使得本地修复无效。 

## 方法

 蛮力观点很简单。 A、B 和 C 中的每一个都可以独立地映射到“(”或“)”，从而给出 2³ = 8 个分配。 对于每个赋值，我们构造结果括号序列，并通过从左到右扫描并维护一个平衡计数器来检查它是否是常规括号序列，该计数器决不能为负并且必须以零结束。 

这是可行的，因为可以在 O(n) 内验证常规括号序列，并且候选映射的数量是恒定的。 因此，每个测试用例的总成本是常数乘以 n。 

试图聪明地根据位置贪婪地分配括号是行不通的，因为约束将全局范围内出现的所有字母耦合起来。 该结构足够小，以至于枚举在任何优化需求中都占主导地位。

 ## 算法演练

 我们将问题简化为测试从字母到括号的所有可能的分配。 

1. 枚举从{A,B,C}到{“(”,“)”}的所有8个映射。 这是使用 3 位掩码完成的，其中每一位确定一个字母的括号类型。 这确保我们涵盖所有可能的全球任务。 
2. 对于每个映射，通过根据映射替换字符串中的每个字符来构造或模拟括号序列。 我们不需要显式地构建字符串； 我们可以直接计算余额。 
3. 从左到右扫描字符串，同时维护一个计数器`bal`。 当我们看到“(”时，我们就增加它；当我们看到“)”时，我们就减少它。 
4. 如果在任何时候`bal`变为负数，序列无效，我们立即停止检查此映射。 这是必要的，因为右括号多于左括号的前缀稍后无法修复。 
5. 扫描完成后，检查是否`bal`等于零。 如果是，映射会产生一个有效的正则括号序列，因此我们可以输出“YES”。 
6. 如果映射不起作用，则输出“NO”。 

### 为什么它有效

 通过为三个字母中的每一个选择括号类型来完整描述任何有效的分配。 不存在隐藏的自由度。 括号序列上的前缀条件既是必要的也是充分的：当且仅当其运行平衡永远不会低于零并且以零结束时，序列才是规则的。 由于我们详尽地测试了所有可能的分配，因此我们不会错过有效的配置，并且每个无效分配在违反前缀条件时都会被拒绝。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_valid(s, mp):
    bal = 0
    for ch in s:
        if mp[ch]:
            bal += 1
        else:
            bal -= 1
        if bal < 0:
            return False
    return bal == 0

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()

        letters = ['A', 'B', 'C']

        ok = False
        for mask in range(8):
            mp = {}
            for i, c in enumerate(letters):
                mp[c] = (mask >> i) & 1  # 1 -> '(', 0 -> ')'

            if is_valid(s, mp):
                ok = True
                break

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```该解决方案使用位掩码迭代所有 8 个映射。 每个位对字母是否映射到“(”或“)”进行编码。 辅助函数通过维持运行平衡并在变为负值时尽早拒绝来检查线性时间的有效性。 尽早退出很重要，但由于限制较小，并非绝对必要。 

为每个掩码重建映射字典，这很好，因为只存在三个键。 另一种选择是预先计算大小为 8 × 3 的数组，但它不会改变复杂性。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def is_valid(s, mp):
        bal = 0
        for ch in s:
            bal += 1 if mp[ch] else -1
            if bal < 0:
                return False
        return bal == 0

    def solve():
        t = int(input())
        for _ in range(t):
            s = input().strip()
            letters = ['A', 'B', 'C']

            ok = False
            for mask in range(8):
                mp = {}
                for i, c in enumerate(letters):
                    mp[c] = (mask >> i) & 1
                if is_valid(s, mp):
                    ok = True
                    break
            print("YES" if ok else "NO")

    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

 ## 边缘情况

 关键的边缘情况是所有字符都相同。 例如`AAAAAA`强制每个位置都接受相同的括号。 如果映射到“(”，则序列永远不会闭合；如果映射到“)”，则它立即变得无效。 该算法正确地测试了两者并拒绝了两者，因为两者都没有产生零最终余额。 

另一种情况是交替结构，例如`ABABAB`。 这里只有某些映射允许前缀稳定性。 在执行期间，仅对于将 A 和 B 对齐到相反括号类型的赋值，平衡跟踪保持非负，枚举会自动捕获该类型。 

第三种情况是短字符串，例如`AB`。 即使计数是平衡的，也只有一个映射产生有效的序列。 扫描正确地拒绝了立即产生前缀下降到 -1 的映射，这是最早可能的故障点。
