 ## 解决方案
 ## 问题理解

 给定一个数组，我们考虑通过删除任何元素子集同时保持顺序而形成的每个子序列。 对于每个结果序列，我们计算两个相邻元素相等的次数。 这个计数称为闪光次数。 任务是计算有多少子序列正好产生 k 个闪光。 

思考子序列的一个有用方法是通过它的运行。 游程是相等值的最大块。 如果子序列具有长度为 L 的游程，则该游程贡献 L 减去一次闪烁。 对所有运行进行求和即可得出闪烁总数。 同样，如果子序列的长度为 m 并且运行 r，则闪存计数为 m 减去 r。 

这种重新表述很重要，因为它表明闪烁完全取决于我们延长运行与开始新运行的频率，而不是由原始数组中的绝对位置决定。 

与通常的序列问题相比，约束在不同的方向上是严格的。 数组长度可以达到二十万，而k最多为二十。 这强烈建议采用动态规划方法，保持 k 的较小维度并在结构上进行聚合。 显式跟踪任意子序列甚至维护每个位置对状态的解决方案立即太大。 

一个天真的尝试会生成所有子序列并直接计算闪存。 这已经涉及 2^n 个对象，甚至对于 n 个大约 30 个对象来说这也是不可行的。 另一个常见的失败是尝试在不压缩“最后一个值”维度的情况下对子序列进行 DP，这将需要显式地跟踪所有值之间的转换并在内存中快速爆炸。 

当仅考虑“相等相邻对的数量”时，会出现一个更微妙的陷阱。 人们可能会尝试计算原始数组中相等元素所贡献的对，但子序列中的邻接关系不是数组中的邻接关系，因此这会丢失所有结构。 

## 方法

 蛮力的想法很简单。 枚举每个子序列，对其进行模拟，并通过扫描相邻对来对闪烁进行计数。 这在概念上是可行的，因为它直接遵循定义，但需要指数时间。 对于 n 高达 200000 的情况，甚至不可能表示所有子序列。 

关键的结构见解是，我们可以增量构建子序列，同时仅跟踪两条信息：最后选择的值和迄今为止的闪烁次数。 当我们追加一个新元素时，我们要么启动一个新的子序列，继续具有相同值的现有子序列并增加闪存计数，要么切换到不同的值并保持闪存计数不变。 

困难在于“最后一个值”涵盖所有不同的值，因此朴素的 DP 需要每个值 O(nk) 个状态，这对于在朴素的 2D 数组中全局维护来说太大了。 重要的观察是，在位置 i 处到固定值 x 的转换仅取决于所有先前最后值的聚合计数，而不是它们的个体身份。 这使我们能够维护每个值的 DP 数组，但使用 k 上的全局总和来更新它们。 

我们从左到右处理数组。 对于每个值 v，我们维护 dp[v][t]，即以值 v 结尾并且恰好有 t 闪烁的子序列的数量。 我们还维护total[t]，即所有v 的dp[v][t] 之和。 

当我们处理新出现的 x 时，只有 dp[x] 发生变化。 所有其他 dp[v] 仍然有效，因为它们不依赖于 x 当前是否正在处理； x 只添加以 x 结尾的新子序列。 

这个局部性使得解在 n 中保持线性且因子 k 很小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 具有值状态的最优 DP | O(nk) | O(nk) | O(nk) | O(nk) | 已接受 |

 ## 算法演练

我们维护两种结构。 第一个是 dp[v]，一个大小为 k+1 的数组，存储以 v 结尾的子序列的计数。第二个是total[t]，是 dp[v][t] 的所有 v 的总和。 

我们在概念上也包含空子序列，但我们仅将其视为启动机制，而不是将其显式存储在 dp 中。 

### 步骤

 1. 将所有 t 的 dp[v] 初始化为空数组，将 Total[t] 初始化为零。 这对应于尚未处理任何元素。 
2. 从左到右处理数组。 在位置 i 处，令当前值为 x。 
3. 为值 x 创建一个新的贡献数组 add[t]。 这将存储包含 a[i] 后以 x 结尾的所有子序列。 
4. 开始一个仅由a[i]组成的新子序列。 这有助于 add[0] += 1，因为单个元素产生零闪烁。 
5. 扩展以任何不同于 x 的值结尾的现有子序列。 对于固定的 t，total[t] 的所有子序列都可以扩展，但是那些已经以 x 结尾的子序列是特殊的，因为将 x 扩展到 x 会增加闪烁。 因此，我们使用total[t] - dp[x][t]作为以不同值结尾的子序列的数量，并在不改变t的情况下扩展它们。 
6. 扩展以 x 结尾的子序列。 当我们再次追加 x 时，每个具有 t-1 次闪烁的子序列都会成为具有 t 次闪烁的子序列，因此我们将 dp[x][t-1] 添加到 add[t] 中。 
7. 计算完 add 后，我们通过减去旧的 dp[x] 并添加从 add 导出的新 dp[x] 来更新总计。 
8. 将 dp[x] 替换为 add。 

### 为什么它有效

 在任何点，dp[v][t] 准确地表示迄今为止看到的所有子序列，其最后一个元素是 v 并且其闪存计数是 t。 每个子序列要么不涉及当前元素，要么以当前元素结束。 当处理新出现的 x 时，通过从 x 处开始或将 x 附加到先前有效的子序列来捕获每个有效扩展。 分解为“在 x 处结束”和“不在 x 处结束”是详尽且不相交的，因此每个子序列都只计算一次，并且不会错过任何转换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        dp = {}
        total = [0] * (k + 1)

        for x in a:
            if x not in dp:
                dp[x] = [0] * (k + 1)

            old = dp[x]
            add = [0] * (k + 1)

            add[0] += 1

            for tval in range(k + 1):
                if total[tval]:
                    base = total[tval] - old[tval]
                    if base:
                        add[tval] += base

            for tval in range(1, k + 1):
                add[tval] += old[tval - 1]

            for tval in range(k + 1):
                delta = add[tval] - old[tval]
                if delta:
                    total[tval] += delta
                    old[tval] = add[tval]
                else:
                    old[tval] = add[tval]

        print(total[k] % 998244353)

if __name__ == "__main__":
    solve()
```实现的核心是每值DP表和全局总数组。 更新步骤小心地仅隔离当前元素值的影响，确保其他 dp 块保持不变。 减法`total[t] - old[t]`是避免重复计算已经以相同值结束的子序列的关键机制。 

k 上的循环保持足够小以保持高效，因为 k 以 200 为界，并且所有操作在该维度上都是线性的。 

## 工作示例

 考虑数组`[1, 2, 2, 1]`和`k = 1`。 

我们只跟踪非零条目。 

| 步骤| x| 更新后的 dp[x] | 总计[0] | 总计[1] |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | [1, 0] | 1 | 0 |
 | 2 | 2 | [1, 0] | 3 | 0 |
 | 3 | 2 | [2, 1] | 5 | 1 |
 | 4 | 1 | [2, 1] | 8 | 5 |

 处理完所有元素后，total[1] 等于 5，正好与一次 flash 的子序列数匹配。 

现在考虑`[1, 1, 1]`和`k = 0`。 每个子序列都没有闪烁，除非它在子序列中包含重复的邻接，只有当我们选择连续的相等贡献时才会发生这种情况。 

| 步骤| x| 更新后的 dp[x] | 总计[0] |
 | --- | --- | --- | --- |
 | 1 | 1 | [1] | 1 |
 | 2 | 1 | [2] | 2 |
 | 3 | 1 | [3] | 3 |

 当 k = 0 时，最终答案是 3，对应于单次运行中由相同值组成的所有非空子序列。

 | 测量 | 复杂性 | 说明|

 所有测试用例的 n 总和以 200000 为界，k 最多为 200，因此 DP 转换的数量保持在几千万以内，这完全符合时间限制。 由于 k 维度有界，因此在大内存限制下，内存使用量仍然可以接受。

 ## 边缘情况

 最小单元素数组显示算法是否使用由贡献零闪烁的一个元素组成的子序列正确初始化 dp。 在这种情况下，dp 为该值创建一个新条目，分配 add[0] = 1，total[0] 变为 1，从而产生正确的结果。 

仅当在同一值内扩展时，具有所有相同值的数组才能测试重复更新是否正确累积闪烁。 每次处理相同的值时，dp[x][t-1] 转换会增加闪存计数，并且不会出现交叉值转换干扰。 

具有所有不同值的数组强调“切换值”逻辑。 由于在处理每个 x 之前 dp[x] 始终为零，因此每个子序列扩展仅来自total[t]，并且 dp[x] 减法并不重要。 该算法简化为 k = 0 时的简单子序列计数，在 k = 0 时正确生成 2^n - 1 个子序列。
