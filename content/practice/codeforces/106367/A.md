 ## 解决方案
 ## 问题理解

 我们得到了以标准十六进制 Web 格式编写的 RGB 颜色序列，其中每种颜色以`#`后跟六个小写十六进制字符。 这六个字符编码三个整数：红色、绿色和蓝色，每个整数的范围为 0 到 255，每个通道存储为两个十六进制数字。 

对于每种输入颜色，我们必须构建其补色。 当每个相应的 RGB 分量之和为 255 时，两种颜色是互补的。换句话说，如果原始颜色有分量`(R, G, B)`，输出颜色必须是`(255 − R, 255 − G, 255 − B)`，然后转换回格式正确的十六进制字符串，其中包含小写字母和前导零（如果需要）。 

就测试用例而言，输入大小很大，最多 10^4。 每个测试用例都是独立处理的，每个操作的每种颜色的时间都是恒定的。 这排除了任何二次或涉及每个测试用例超过 O(1) 的重复字符串扫描的情况。 直接对每个角色进行转换就足够了。 

一个微妙的失败案例来自格式化。 每个 RGB 分量必须始终使用两个十六进制数字来表示。 如果忽略这一点，像 0 这样的值就会变成`0`而不是`00`，这打破了所需的固定长度格式。 

例如，如果输入是`#000000`，正确的输出是`#ffffff`。 忘记填充的幼稚实现可能会产生`#fff`，这在规范下是无效的。 

另一个边缘细节是区分大小写。 输出必须是小写十六进制。 使用大写字母如`#E0E1CC`即使数字正确也会被拒绝。 

## 方法

 强力解释是通过手动解析每个字符将每个十六进制数字字符串转换为整数颜色值，然后计算 255 减去每个通道，最后通过重复将整数转换回十六进制来重建字符串。 每个测试用例的时间复杂度为 O(1)，但如果实现效率低下，例如通过重复连接字符串或使用缓慢的手动基数转换，则由于在最多 10^4 个输入上重复进行字符操作，它在实践中可能会降低性能。 

关键的观察结果是每个通道都是独立的并且始终限制在 [0, 255] 内，因此 Python 内置的整数解析和格式化函数是足够且最佳的。 我们只需要提取固定的子字符串，将它们转换一次，从 255 中减去，然后使用两位十六进制格式进行格式化。 这完全避免了手动逐位处理。 

输入的结构保证了恒定大小的字符串，因此最佳解决方案只是每个测试用例的直接转换，无需辅助数据结构。

 ## 算法演练

 我们独立处理每个测试用例。 

1.读取颜色字符串`s`。 它总是具有以下形式`#RRGGBB`。 这种固定结构允许直接切片而无需扫描。 
2.使用提取红色成分`s[1:3]`、绿色利用`s[3:5]`和蓝色使用`s[5:7]`。 每个子字符串恰好是两个十六进制字符，这保证了有效的解析。 
3. 使用 base-16 转换将每个子字符串从十六进制转换为整数。 这给出了`(R, G, B)`以数字形式。 
4. 通过从 255 中减去来计算每个通道的补数，产生`(255 − R, 255 − G, 255 − B)`。 此步骤对于每个通道都是独立的，反映了问题的互补性定义。 
5. 将每个结果整数转换回两个字符的小写十六进制字符串。 如果该值小于 16，则必须包含前导零。 这种固定宽度格式保留了所需的 RGB 编码。 
6. 按顺序连接结果并添加到前面`#`形成最终的输出字符串。 

### 为什么它有效

 每个 RGB 分量在固定的 8 位范围内独立编码。 转变`x → 255 − x`是该域的对合，这意味着应用两次会返回原始值。 由于十六进制表示是两者之间的双射`[0, 255]`和`00`到`ff`、转换为整数、转换并格式化回来可以准确地保留正确性。 不存在跨组件交互，因此独立处理通道不会引入不一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        s = input().strip()

        r = int(s[1:3], 16)
        g = int(s[3:5], 16)
        b = int(s[5:7], 16)

        cr = 255 - r
        cg = 255 - g
        cb = 255 - b

        out.append("#" + format(cr, "02x") + format(cg, "02x") + format(cb, "02x"))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案依赖于固定的切片位置，这避免了任何每个字符的循环开销。 每个`int(..., 16)`即使对于前导零，调用也可以安全地处理转换。 这`format(x, "02x")`确保小写输出和强制零填充。 

一个常见的实施错误是使用`hex(x)`直接生成字符串，如`0xa`而不是`0a`。 除非手动进行后处理，否则这会破坏格式。 另一个微妙的问题是遗忘`.strip()`在输入行上，这可能会导致换行符干扰切片。

 ## 边缘情况

 全零颜色`#000000`演示了对前导零十六进制解析和格式化的正确处理。 每个通道变为 255，必须打印为`ff`，确认没有丢失任何填充逻辑。 

全白的颜色`#ffffff`检查相反的极端。 每个通道都变为0，必须显示为`00`。 删除前导零的幼稚格式化程序会错误地输出`#0`，但固定宽度格式可确保正确性。 

混合值的情况，例如`#0f10f0`确保独立通道处理不会跨组件干扰。 每个字节都单独反转，保持 RGB 位置之间的对齐并防止意外重新排序或共享计算错误。
