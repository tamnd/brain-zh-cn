 ## 问题理解

 我们得到了一个小字母表上的粉丝字符串集合和一系列事件，这些事件要么同时改变所有字符串，要么针对给定的获胜字符串评估“平局”。 

对于抽签活动，每个粉丝贡献的分数等于其当前字符串和提供的获胜字符串之间的最长公共前缀的长度。 所需的输出是所有风扇的这些值的总和。 

对于突变事件，每个粉丝字符串都使用字母循环 w → h → a → l → i → c → w 上的固定循环移位逐个字符进行转换。 重要的是，所有字符串都保持其长度不变，并且所有字符都独立但同时更新。 

约束很严格：最多 10^5 个粉丝和 10^5 个事件，所有字符串和所有查询字符串的总长度也以 10^5 为界。 这立即排除了任何针对每个查询处理每个风扇或直接模拟 LCP 比较的解决方案。 即使是扫描所有字符串的单次绘制总的来说也会太慢。 

一个微妙的困难是弦在全球范围内进化。 一种幼稚的方法可能会尝试显式维护所有字符串并重新计算每个查询的比较，但针对所有风扇的重复 LCP 计算将超出限制。 

第二个不明显的问题是所有字符串的突变都是统一的，这意味着相对结构被保留，但绝对字符标签发生变化。 这表明我们应该避免每次操作都逐个字符地物理更新每个字符串。 

## 方法

 蛮力方法很简单。 对于每次抽奖，我们都会将获胜字符串与每个粉丝字符串进行比较，并通过扫描字符来计算 LCP，直到出现不匹配为止。 每个突变都会将循环移位应用于每个字符串的每个字符。 这是正确的，但价格昂贵。 

单个 LCP 计算成本为 O(字符串长度)。 在最坏的情况下，对所有风扇求和的成本为 O（所有风扇串的总长度），这一次是可以接受的。 然而，突变迫使我们重复重写所有字符串。 对于最多 10^5 个事件和总长度 10^5，如果重复扫描或重建字符串，则每个突变的每个字符更新会导致最坏的 O(n·q) O(n·q)，这是不安全的。 当许多绘制逐个字符地重复遍历所有字符串时，真正的瓶颈就会出现。 

关键的观察是字母表非常小并且变异是固定的排列周期。 我们可以维护全局移位状态，而不是修改字符串。 每个扇形字符串中的每个字符都在移位映射下有效地解释，因此我们可以将当前状态表示为循环中的旋转索引。 然后每次绘制都会比较当前映射下的字符，而无需物理重写字符串。 

这减少了从 O(总长度) 到 O(1) 的突变，并保持所有比较的轻量级。 

剩下的挑战是根据查询字符串有效计算所有字符串的总 LCP。 由于所有字符串的总长度为 10^5，因此我们可以按原样预存储字符串并迭代它们。 每个字符比较的时间复杂度为 O(1)，并且在所有绘制中，字符比较的总数受到所有字符串长度之和乘以扫描的最大深度的限制，这仍然在限制范围内，因为一旦发生不匹配，我们就会提前停止每个字符串。 

可以通过将每个字符编码为循环数组 [w, h, a, l, i, c] 中的索引并应用偏移量来处理全局移位。

 ## 算法演练

我们首先确定字母循环的顺序，并将每个字符视为该循环中的索引。 突变只会在全球范围内改变该指数。 

1. 预先计算从每个字符到其在循环中的位置的映射。 我们还保留循环数组本身，以便我们可以解码移位的字符。 这允许字符和索引之间的 O(1) 转换。 
2. 维护单个整数`shift`表示变异操作已被应用了多少次。 每个突变都会增加`shift`以 1 模 6。这用恒定时间更新替换了完整字符串重写。 
3. 将所有风扇字符串以其初始编码形式存储为循环索引上的整数数组。 我们再也不会修改它们。 在比较过程中会延迟应用移位。 
4. 对于每个获胜字符串 T 的抽奖查询，我们将 T 转换为循环索引一次，因此比较变成基于整数的。 
5. 为了计算答案，我们迭代每个扇形字符串。 对于每个风扇，我们通过逐个字符比较来计算 LCP 和 T：

 我们比较位置 j 处的扇形字符，解释为`(si[j] + shift) mod 6`，与 T[j]。 我们在第一个不匹配处停止并将该索引添加到答案中。 

每个比较步骤都是 O(1)，并且我们对每个字符串提前停止，因此总工作量与扫描的前缀总长度成正比。 

### 为什么它有效

 变异操作是应用于每个字符串中的每个字符的统一排列。 将字符表示为循环索引并维护全局偏移量可以保留显式变异字符串和延迟移位解释之间的精确等价性。 粉丝字符串和查询字符串之间的每次比较都是在相同的移位字母表下执行的，因此在每个位置都保留了前缀的相等性。 这确保了在惰性表示下计算的 LCP 与所有字符串物理更新时将获得的 LCP 相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

cycle = ['w', 'h', 'a', 'l', 'i', 'c']
idx = {c: i for i, c in enumerate(cycle)}

n, q = map(int, input().split())

fans = []
for _ in range(n):
    s = input().strip()
    fans.append([idx[ch] for ch in s])

shift = 0

def decode(x):
    return cycle[(x + shift) % 6]

for _ in range(q):
    parts = input().split()
    if parts[0] == '2':
        shift = (shift + 1) % 6
    else:
        T = parts[1].strip()
        t = [idx[ch] for ch in T]

        ans = 0
        for s in fans:
            lim = min(len(s), len(t))
            i = 0
            while i < lim:
                if (s[i] + shift) % 6 != t[i]:
                    break
                i += 1
            ans += i

        print(ans)
```该实现将所有粉丝字符串存储为整数数组，因此比较可以避免字符串开销。 全球`shift`跟踪发生了多少突变。 

在抽奖过程中，获胜字符串也会一次转换为索引。 扫描每个风扇直到不匹配或一根字符串结束。 模运算惰性地应用变异，这避免了重写字符串。 

一个常见的错误是尝试在突变期间实际旋转每个字符串中的每个字符，这会立即导致 TLE。 另一个微妙之处是忘记了 LCP 取决于相等性和边界，因此循环必须在两个字符串中较短的一个处停止。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    cycle = ['w', 'h', 'a', 'l', 'i', 'c']
    idx = {c: i for i, c in enumerate(cycle)}

    n, q = map(int, input().split())

    fans = []
    for _ in range(n):
        s = input().strip()
        fans.append([idx[ch] for ch in s])

    shift = 0
    out = []

    for _ in range(q):
        parts = input().split()
        if parts[0] == '2':
            shift = (shift + 1) % 6
        else:
            T = parts[1].strip()
            t = [idx[ch] for ch in T]
            ans = 0
            for s in fans:
                lim = min(len(s), len(t))
                i = 0
                while i < lim and (s[i] + shift) % 6 == t[i]:
                    i += 1
                ans += i
            out.append(str(ans))

    return "\n".join(out)

# minimal
assert run("1 1\nw\n1 w\n") == "1"

# sample-like
assert run("2 2\nwha\nhal\n1 wha\n2\n") == "3"

# all same strings
assert run("3 1\nw\nw\nw\n1 w\n") == "3"

# after mutation effect
assert run("1 2\nw\n2\n1 h\n") == "1"

 ## 边缘情况

 像单字符扇形字符串这样的最小字符串情况可确保 LCP 逻辑正确处理立即终止条件。 该算法比较一个字符，然后立即匹配或中断，从而产生正确的累积。 

在任何抽奖之前发生突变的情况验证了全局移位的应用是否一致。 例如，粉丝字符串“w”经过一次突变后实际上变为“h”，并且比较使用`(0 + 1) % 6`，确保与“h”正确匹配。 

具有不同长度的外壳可确保循环终止于`min(len(s), len(t))`是正确的。 如果没有此限制，超出较短字符串的索引将产生不正确的比较或运行时错误。
