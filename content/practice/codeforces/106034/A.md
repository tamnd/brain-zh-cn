 ## 解决方案
 # 问题理解

 问题在于比较以几种可能的人类友好格式编写的电话号码。 Vasya 想要向他的联系人添加一个新号码，但他需要知道三个现有记录中的每一个是否都指向同一个实际电话号码。 

电话号码由三位数的区域/运营商代码和七位数的用户号码组成。 该代码可以显式编写或省略，在这种情况下，应将其视为`495`。 国家/地区前缀可以显示为`+7`或者`8`，和分隔符`-`可以插入任意数字之间。 代码两边的括号也是允许的。 

输入包含 Vasya 要添加的一个电话号码，后跟已存储的三个电话号码。 对于每个存储的数字，我们需要输出`YES`如果它代表与新号码完全相同的代码和用户号码，否则输出`NO`。 

限制很小，因为每个数字最多只包含几十个字符。 这意味着我们不需要高级数据结构或繁重的字符串算法。 对字符进行线性扫描就足够了，即使扫描几次也远远低于可用的限制。 重要的部分不是性能，而是将所有可能的格式正确规范为一种通用表示形式。 

棘手的情况来自于相同数字的不同出现方式。 例如：```
Input:
8(495)430-23-97
+7-4-9-5-43-023-97
4-3-0-2-3-9-7
```前两个数字代表相同的电话号码，因为`8`和`+7`是等价的，代码是`495`。 第三个数字没有代码，所以它的代码变成`495`，也是一样的。 仅删除破折号但保持前缀不变的解决方案会错误地分隔这些情况。 

另一个边缘情况是代码丢失：```
Input:
4302397
84954302397
```正确的输出是`YES`，因为第一个数字应该解释为`4954302397`，第二个也是`4954302397`转换后`8`前缀。 粗心的实现可能只比较可见的数字而错过隐式代码。 

当删除符号后的数字有十一位时，会出现不同的错误：```
Input:
84951234567
1234567
```第二个数字不仅仅是最后七位数字。 它也有默认代码`495`，所以正确的比较是`4951234567`和`4951234567`，不在不完整的字符串之间。 忽略默认代码会产生漏报。 

# 方法

 最简单的方法是在删除分隔符后尝试直接比较字符串。 这很诱人，因为输入很小。 我们可以删除每一个`-`，去掉括号，然后检查剩余的字符串是否匹配。 这在某些情况下是正确的，因为格式化字符不会影响实际数字。 

问题在于可见的表示并不是真实的数据。 同一电话号码可以有不同的前缀，并且可以省略代码。 暴力方法需要模拟输入格式的每种可能的解释。 如果只有几个字符，这仍然是可能的，但它是不必要的复杂性并且可能会出错。 

关键的观察结果是，每条有效的电话记录都描述完全相同的两条信息：三位数代码和七位数用户号码。 如果我们将每个输入字符串转换为这两部分，比较就变得微不足道了。 

删除格式符号后，剩余的数字具有两种形状之一。 如果长度为 7，则省略代码并在前面添加`495`。 如果长度为 11，则第一个数字是国家/地区前缀（`8`），接下来的三位数字是代码。 最后七位数字始终是订户号码。 然后可以将相同的标准化十位数字表示用于所有比较。 

蛮力思想之所以有效，是因为输入很小，但它在概念上失败了，因为它比较的是表示而不是含义。 规范化步骤将问题从具有多种情况的字符串匹配问题转换为简单的相等检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每次比较 O(k) | O(k) | 已接受但容易出错 |
 | 最佳 | 每个数字 O(k) | O(k) | 已接受 |

 这里`k`是电话字符串的长度。 自从`k`受小输入格式的限制，两者都很快，但标准化是干净的解决方案。 

## 算法演练

 1. 读取 Vasya 想要添加的电话号码并将其转换为规范化形式。 规范化形式将是一个十位数字的字符串，其中包含三位数字的代码，后跟七位数字的订户号码。 
2. 要标准化数字，请先删除所有非数字字符。 完成此步骤后，仅保留有意义的数字。 
3. 如果清理后的字符串有七位数字，则添加`495`到开始。 这处理未明确编写代码的数字。 
4. 如果清理后的字符串有十一位数字，则删除前导`8`或者`7`国家代表并保留其余十位数字。 这些数字的前三位是代码，后七位是订户号码。 
5. 以相同的方式标准化三个存储的电话号码中的每一个。 
6. 将每个标准化存储数字与标准化目标数字进行比较。 打印`YES`当它们相等并且`NO`否则。 

这样做的原因是规范化消除了仅与格式有关的所有差异。 转换后，当两个数字的真实代码和用户号码相等时，两个数字完全相等。 

不变量是每个规范化字符串代表一个且仅一个实际的电话号码。 在算法过程中，我们从不比较不完整或格式化的表示，因此相同数字的不同拼写总是会折叠为相同的值。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def normalize(s):
    digits = ''.join(c for c in s if c.isdigit())

    if len(digits) == 7:
        return '495' + digits

    if digits[0] in '78':
        digits = digits[1:]

    return digits

def solve():
    target = normalize(input().strip())

    ans = []
    for _ in range(3):
        cur = normalize(input().strip())
        ans.append("YES" if cur == target else "NO")

    print('\n'.join(ans))

if __name__ == "__main__":
    solve()
```这`normalize`功能是解决方案的全部思想。 首先，它通过仅保留数字字符来删除破折号和括号。 电话格式保证剩余的字符串是七位或十一位数字。 

七位数的情况是通过插入默认代码来处理的。 对于十一位数字的情况，第一位数字只是国家/地区前缀，因此在比较之前将其删除。 

比较阶段故意简单。 所有格式决定都已解决，因此字符串相等就是电话号码相等。 

原始字符串中的固定位置不存在索引风险，因为分隔符可能出现在任何地方。 该代码仅依赖于已清理的数字字符串，其中格式得到保证。

 # 边缘情况

 对于第一个边缘情况，请考虑：```
4302397
4954302397
```第一个数字被清理成`4302397`。 该算法检测七位数字并创建`4954302397`。 第二个数字被清理并删除前缀，留下相同的标准化值，所以答案是`YES`。 

对于前缀问题：```
+7(495)4302397
84954302397
```第一个数字变为`74954302397`删除符号后，第二个变成`84954302397`。 在这两种情况下，前导国家/地区数字都会被删除，留下`4954302397`，所以比较成功。 

对于错误的代码：```
84991234567
84981234567
```第一个标准化为`4991234567`，而第二个变成`4981234567`。 订阅者部分相同，但代码不同，因此算法正确打印`NO`。
