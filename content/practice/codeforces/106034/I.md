 ## 解决方案
 ## 问题理解

 我们得到一系列从位置 1 到位置 n 排列成一直线的平台。 每个平台都有一个高度。 角色从平台 1 开始，想要通过一系列跳跃到达平台 n。 

仅当两个条件同时成立时，才允许从平台 i 跳转到平台 j。 首先，索引距离不得超过 d，因此 j 必须位于窗口 i - d 到 i + d 内。 其次，目标平台与当前平台相比不能太高，这意味着高度增加 a[j] - a[i] 不得超过 h。 下降始终是允许的，因为下降没有限制。 

任务是计算到达平台 n 所需的最小跳跃次数，或者确定这是不可能的。 

输入大小限制为 n 和 d，最多 10,000。 这立即以简单的方式排除了所有平台对上的任何 O(n²) 转换。 检查每个节点的每个可达对的解决方案在最坏的情况下将执行大约 10⁸ 操作，这在严格的时间限制下在 Python 中是边界，但通常太慢，特别是在约束检查的额外开销下。 

高度数组引入了一个重要的不对称性：只有向上移动超过 h 才会阻止跳跃。 这意味着我们不能将边缘视为均匀或对称； 我们需要一个能够通过索引范围和高度条件有效过滤候选者的结构。 

当所有高度都相同时，就会出现微妙的边缘情况。 在这种情况下，距离 d 内的每个平台都是可达的，并且该图成为稠密区间图。 显式构建邻接列表的朴素 BFS 将由于内存或时间爆炸而失败。 

当高度严格随索引增加且 h 较小时，会出现另一种边缘情况。 那么即使索引很接近，每次向前跳跃也可能被阻止，并且答案变为-1。 任何假设“局部移动总是可能的”的解决方案都会错误地生成一条路径。 

## 方法

 直接解释构建一个图表，其中每个平台 i 连接到每个平台 j，使得 |i - j| ≤ d 且 a[j] - a[i] ≤ h。 在此图上运行 BFS 会给出正确的答案，因为每条边的成本相等。 

问题在于，在最坏的情况下，该图最多可以有 n·d 条边。 当 n = 10⁴ 和 d = 10⁴ 时，这会退化为 10⁸ 边，这对于显式构造或迭代每个节点来说太大了。 即使 BFS 本身在边缘上是线性的，转移成本也占主导地位。 

关键的观察是 BFS 不要求我们显式枚举所有邻居。 对于每个平台，我们只需要在滑动索引窗口内找到下一个也满足高度约束的未访问平台。 一旦平台被处理，就不应重新考虑。 这使我们能够维护一组动态的“未访问的候选者”，并在访问后将其删除。 

我们维护一个存储所有未访问索引的结构。 对于每个平台 i，我们仅扫描 [i+1, i+d] 范围内的节点并跳过已处理的节点。 每个节点都被删除一次，因此即使我们扫描多次，总工作量仍保持线性，最多可达对数因子，具体取决于容器。 

遍历期间会检查高度条件，并且只有有效的转换才会排队到 BFS 中。 

这将问题从显式图遍历转变为对不断缩小的候选集进行受控窗口扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力图 + BFS | O(n·d) | O(n·d) | 太慢/内存太重 |
 | 具有未访问集的滑动窗口 BFS | 最坏情况为 O(n·d)，但实际摊销接近 O(n log n) / O(n) | O(n) | 已接受 |

 ## 算法演练

1. 初始化一个距离数组，将所有值设置为 -1 并设置 distance[1] = 0，因为我们从第一个平台开始。 
2.维护一个BFS队列并插入平台1。 
3. 维护一个包含从 1 到 n 的所有尚未访问的索引的结构。 这种结构允许我们迭代潜在的下一个位置，而无需重新访问已处理的节点。 
4. 当队列不为空时，删除当前平台i。 
5. 对于 (i+1 到 i+d) 范围内的每个候选 j，检查 j 是否仍未被访问以及是否 a[j] - a[i] ≤ h。 如果两者都成立，则赋值 distance[j] = distance[i] + 1，将 j 推入队列，并将其从未访问的结构中删除。 
6. 重复，直到处理完所有可达节点或达到目标n。 
7. 输出距离[n]，它是最小跳跃次数，如果无法到达则为-1。 

关键的设计选择是，一旦平台被访问，它就会从候选集中永久删除。 这确保了没有平台被处理超过一次，即使它可能作为不同窗口的一部分被扫描多次。 

### 为什么它有效

 在任何时刻，BFS 都会按照跳转次数递增的顺序处理节点。 未访问的结构保证了每个平台在第一次被发现时就被分配了最小可能的距离。 因为所有边都代表一次跳跃，所以 BFS 分层属性完全成立。 以后无法找到更短的路径，因为所有未来的转换都对应于相同或更大的 BFS 深度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, d, h = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    dist = [-1] * (n + 1)
    dist[1] = 0

    q = deque([1])

    # we keep a simple list of "alive" indices
    alive = set(range(1, n + 1))
    alive.remove(1)

    while q:
        i = q.popleft()

        # scan only forward window
        to_remove = []
        for j in range(i + 1, min(n + 1, i + d + 1)):
            if j in alive and a[j] - a[i] <= h:
                dist[j] = dist[i] + 1
                q.append(j)
                to_remove.append(j)

        for j in to_remove:
            alive.remove(j)

    print(dist[n])

if __name__ == "__main__":
    solve()
```BFS 是标准的，但重要的实现细节是我们如何避免重新访问节点。 这`alive`set 充当全局过滤器，确保每个平台最多排队一次。 临时名单`to_remove`避免在迭代期间修改集合，否则会导致运行时错误或跳过元素。 

内循环仅向前扫描最多 d 个位置，直接匹配约束。 这是唯一使用问题结构的地方； 其他一切都是未加权图中的标准最短路径。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, d, h = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    dist = [-1] * (n + 1)

    q = deque([1])

                q.append(j)
                to_remove.append(j)
        for j in to_remove:
            alive.remove(j)

    return str(dist[n])

 ## 边缘情况

 n = 1 的最小情况检查实现是否正确返回零跳转而不尝试任何 BFS 扩展。 该算法初始化 distance[1] = 0 并立即终止，因为已经达到目标。 

所有向前移动都违反高度约束的完全阻塞情况证实了窗口内的扫描不会错误地假设可达性。 BFS 队列立即清空，将所有剩余距离保留为 -1。 

d 非常大的情况表明，即使窗口跨越整个剩余数组，将扫描限制为 i + d 也是足够的，并且除了限制循环之外不需要额外的优化。 

混合交替高度模式表明，该算法正确应用了不对称约束 a[j] - a[i] ≤ h，防止向上尖峰，同时仍允许向下转换。
