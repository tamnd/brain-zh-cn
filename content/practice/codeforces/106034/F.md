 ## 解决方案
 ## 问题理解

 我们得到了多个独立的测试用例。 每个测试用例描述一组间隔，每个人一个间隔。 人 i 只能被分配一个整数位置，并且该位置必须位于他们的区间内$[l_i, r_i]$。 所有分配的位置必须是不同的。 

另一种看待问题的方法是，我们希望为每个区间选择一个不同的整数，但每个区间限制了哪些整数可以接受。 整数本身是抽象标签，因此只有相对顺序才重要，而不是它们可以达到的事实$10^9$。 

任务是确定是否存在不同整数的分配，使得每个区间都包含分配给它的整数。 

这些约束意味着所有测试用例的间隔总数最多为$2 \cdot 10^5$。 任何每个测试用例都是二次的解决方案都将无法生存。 排序很好，任何带有堆或指针扫描的贪婪算法也很好。 

一些边缘案例暴露了典型的贪婪错误。 例如，如果所有间隔都相同$[1, 10], [1, 10], [1, 10]$，答案立即不可能，因为我们只有 10 个可用整数，但我们需要 3 个不同的选择。 将所有内容分配给同一中点的幼稚方法会错误地声称成功。 

当间隔嵌套时会出现另一种边缘情况，例如$[1, 5], [2, 4], [3, 3]$。 这实际上是可行的，但前提是我们从最受约束的区间向外仔细分配。 任何按输入顺序处理而不考虑紧密性的策略在这里都很容易失败。 

第三种微妙的情况是，例如，许多音程严重重叠但略有变化$[1,2], [2,3], [3,4], [4,5]$。 唯一正确的分配本质上是一条链，不尊重最早完成约束的贪婪决策将破坏可行性。 

## 方法

 强力方法会尝试显式分配整数。 由于值上升到$10^9$，我们可以压缩所有端点，然后尝试使用回溯或二部匹配将区间与整数点一一匹配。 即使在压缩之后，这也成为间隔和坐标之间的最大二分匹配问题。 如果有$n$间隔和最多$2n$坐标，像 Hopcroft-Karp 这样的标准匹配给出了$O(n^{2.5})$在实践中，这对于$2 \cdot 10^5$。 

关键的观察是我们实际上不需要显式地建模坐标。 我们只关心是否可以按顺序贪婪地“消费”可用的整数。 一旦间隔按其右端点排序，我们希望为每个间隔分配仍然可用且位于其范围内的最小可能整数。 这将问题转化为调度式的贪婪过程。 

直觉是，右端点越小的区间受到的约束越多，必须更早满足。 如果我们延迟它，我们可能会以更宽松的间隔消耗它唯一的有效头寸。 

我们从左到右扫描候选整数值，并维护每个点可用的间隔。 优先级队列保持活动间隔按其右端点排序，因此我们总是首先分配当前最小的可行间隔。

 ## 算法演练

 我们首先按左端点对所有间隔进行排序，以便我们知道每个间隔何时符合条件。 然后，我们模拟从尽可能小的向上分配整数位置，但我们从未显式迭代到$10^9$。 相反，我们使用事件隐式地跳过区间边界。 

1. 对间隔进行排序$l_i$。 这让我们可以在区间的范围开始时准确地激活区间。 
2. 维护一个间隔指针和一个最小堆$r_i$。 堆包含所有已开始但尚未分配位置的间隔。 
3. 按升序迭代候选位置，但我们不是盲目迭代，而是尽可能前进到下一个有用的位置。 在每一步中，我们都会推动所有间隔$l_i \le x$到堆中。 
4. 分配职位前$x$，从堆中删除任何间隔$r_i < x$，因为他们不再满足。 如果任何间隔到期而未分配，则答案立即不可能。 
5. 如果堆不为空，则分配当前位置$x$到最小的区间$r_i$。 这个时间间隔如果拖延的话最早就会变得不可行，所以必须优先考虑。 
6. 将该间隔标记为已分配并继续到下一个位置。 
7. 如果所有间隔均分配成功，则返回“Yes”。 

### 为什么它有效

 核心不变量是在每个位置$x$，堆恰好包含仍然可以分配一些有效整数的区间$\ge x$，并且它们都尚未被分配。 其中，选择具有最小右端点的区间是安全的，因为任何可行的解决方案都必须不晚于具有较大右端点的任何区间来分配它。 如果我们未能在最后可能的时刻对其进行分配，则以后将无法修复，因为所有未来的头寸都会更大，因此超出了其范围。 这会产生强制排序，而贪婪选择会尊重全局排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        seg = []
        for i in range(n):
            l, r = map(int, input().split())
            seg.append((l, r))

        seg.sort()
        heap = []
        i = 0
        x = 0
        used = 0
        ok = True

        while used < n:
            if not heap and i < n:
                x = max(x, seg[i][0])

            while i < n and seg[i][0] <= x:
                heapq.heappush(heap, seg[i][1])
                i += 1

            while heap and heap[0] < x:
                heapq.heappop(heap)
                ok = False
                break

            if not ok:
                break

            if heap:
                heapq.heappop(heap)
                used += 1

            x += 1

        out.append("Yes" if ok and used == n else "No")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```实现遵循扫描线逻辑。 变量`x`表示当前被分配的整数。 指针`i`通过排序的间隔前进，推动已到达左边界的所有间隔。 堆只存储正确的端点，因为这足以决定可行性和优先级。 

一个微妙的点是跳跃`x`到`seg[i][0]`当堆为空时。 如果没有这个，模拟将浪费时间迭代没有活动间隔的值。 另一个重要的细节是在尝试分配之前删除过期的间隔； 否则，当某些间隔已经不可能时，我们可能会错误地分配位置。

 ## 边缘情况

 对于相同的间隔，例如$[1,1], [1,1]$，每个区间都竞争同一个位置。 堆将包含具有相同截止时间的多个间隔。 该算法在以下位置分配 1：$x=1$，但立即检测到剩余间隔已过期，正确生成“否”。 

对于嵌套间隔，例如$[1,5], [2,4], [3,3]$，堆总是优先考虑$[3,3]$在$x=3$。 较早的间隔可用时间较长，因此稍后分配它们不会发生冲突。 这显示了最小右端点始终首先被安全处理的不变性。 

对于间隔很宽的情况，例如$[1,1], [100,100]$，指针跳转会跳过未使用的区域，在保证效率的同时保持正确性，因为没有间隔依赖于中间值。
