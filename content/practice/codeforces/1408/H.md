 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，其中值零起着特殊的作用。 我们希望提取尽可能多的不相交的索引三元组，并且每个三元组必须具有非常严格的结构：它必须看起来像一个零，然后是一个非零值，然后是另一个零。 正式地，每个选择的三元组都使用位置$i < j < k$使得两端为零且中间元素非零。 

有两个全局约束耦合不同的三元组。 首先，每个选定的中间元素的值必须不同，因此我们不能在两个不同的三元组中重复使用相同的非零数字。 其次，所有三元组中使用的所有索引都必须是不相交的，因此一旦一个位置在一个三元组中使用，它就永远不可用。 

任务是最大化我们可以构建的这样的三元组的数量。 

限制很大：所有测试用例的总长度最多为 500,000。 这立即排除了任何尝试每个值的所有三元组甚至所有零对的方法。 任何平方项$n$将会失败，甚至$O(n \log n)$在实践中必须小心地线性化。 

当在不考虑全局索引消耗的情况下完成贪婪配对时，会出现微妙的故障模式。 例如，如果零大量但分散，并且值被贪婪地重用，则可能会形成局部有效的三元组，从而阻碍更好的全局分配。 另一个问题是假设每个值独立贡献$\min(\#zeros, 1)$，它忽略了跨值的零竞争。 

作为一个小例子，请考虑：

 输入：```
1
6
0 1 0 2 0 0
```一种天真的每值贪婪方法可能会尝试为 1 和 2 分配它们自己的周围零，但相同的零不能重复使用，因此只能有一个三元组。 

共享资源（零）和排他性中间值之间的相互作用是关键困难。 

## 方法

 暴力策略将尝试枚举每个有效的三元组$(i, j, k)$对于每一个可能的中间位置$j$，然后尝试选择具有不同中间值的最大不相交三元组集合。 这自然会变成最大匹配或集合打包问题。 人们可以将零建模为可重复使用的端点，并将每个非零位置建模为潜在的中心，然后搜索左零和右零的分配。 然而，候选三元组的数量是$O(n^2)$在最坏的情况下，因为每个非零可以与两侧的许多零配对。 即使构建所有候选者也已经太大了。 

关键的观察是我们永远不需要考虑以组合方式在末端使用哪些特定的零。 零是相同的资源； 只有他们的数量才重要。 全局重要的是所选中间位置的左侧和右侧存在多少个可用的零。 

如果我们固定一个中间值$x$，我们只需要知道在考虑到其他三元组已经消耗的零之后，它之前是否存在至少一个零，之后是否存在至少一个零。 这表明以一种为每个选定的中间恰好分配两个零的方式贪婪地处理值。 

我们不再考虑职位的几何结构，而是转向资源分配的观点。 我们在扫描时在数组中维护可用的零，并尝试以确保每个选定的中间恰好消耗两个零的方式分配三元组。 困难在于强制左零和右零来自不同的一侧，这意味着排序问题。 

解决此问题的标准方法是将零视为池，但仍然通过扫描数组来遵守顺序。 当我们考虑中间的候选者时，我们尝试将其与左侧的一个未使用的零和右侧的一个未使用的零进行匹配。 正确的零是关键约束； 它迫使我们确保不会过早地消耗未来的结构。 

这导致了一种贪婪策略：我们扫描并维护可用的零，并且尽可能地尝试形成三元组，但我们确保每个中间最多使用一次，并且每个三元组消耗两个零。 最优性来自于这样一个事实：零是可以互换的，只有它们的总可用性限制了答案。

 ## 算法演练

 我们将问题重新表述为选择尽可能多的中间位置，以便为每个选定的中间位置分配两个不同的零位置，一个在其之前，一个在其之后，并且不会重复使用任何零。 

1. 将数组分为零位置和非零位置。 我们只考虑非零位置作为三元组中间的候选位置。 零是消耗性资源，必须在左右分配之间进行分配。 
2. 从左到右扫描数组，同时保持到目前为止未使用的零的数量。 该值表示当前可用的左端点数量。 
3. 还要维护右侧剩余多少个零。 这可以预先计算为零的后缀计数。 
4. 对于每个位置$j$和$a_j \neq 0$，只有当左边至少有一个未使用的零并且右边至少有一个可用的零时，我们才将其视为候选中间。 这确保我们可以围绕它形成一个有效的三元组。 
5. 如果我们选择中间的$j$，我们立即从左池中消耗一个零，并隐式地从右池中保留一个零。 然后，我们将此中间值标记为已使用，以便不会选择重复项。 
6. 继续扫描，尽可能贪婪地选择有效的中间位置。 所选中位数的数量就是答案。 

关键的设计选择是将右侧零视为递减的预算，而不是明确选择位置。 这样可以避免重复计算并确保可行性。 

它为何有效与全球交换论点有关。 假设最优解选择一组中间值。 我们可以重新排序他们的分配，以便每个中间使用最早可能的可用左零和最晚可能的可用右零。 这种标准化不会降低可行性。 在这种规范化下，每当两种资源都可用时选择中间的贪婪扫描永远不会阻止未来更好的解决方案，因为较早消耗左零只会增加未来的灵活性，而右零仅受总数限制，而不是身份。 

因此，该算法有效地将尽可能多的中间顶点打包到有限的零预算中，每个预算需要在序列中分割两个单位。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        total_zeros = sum(1 for x in a if x == 0)

        left_zeros = 0
        used_middle = set()
        ans = 0

        # remaining zeros to the right
        right_zeros = total_zeros

        for x in a:
            if x == 0:
                left_zeros += 1
                right_zeros -= 1
            else:
                if x in used_middle:
                    continue
                # try to form a triple centered at x
                # need at least 1 zero on each side
                if left_zeros > 0 and right_zeros > 0:
                    used_middle.add(x)
                    ans += 1
                    left_zeros -= 1
                    right_zeros -= 1

        print(ans)

if __name__ == "__main__":
    solve()
```该实现依赖于一次从左到右的扫描。 变量`left_zeros`计算当前位置左侧有多少个零。 变量`right_zeros`被初始化为零的总数，并随着我们的前进而递减，因此它始终反映右侧剩余多少个零。 

当我们遇到非零值时，我们只尝试使用它一次，因为`used_middle`设置，强制中间值的明确性。 如果双方都至少有一个可用的零，我们贪婪地形成一个三元组并从每一方的预算中消耗一个零。 

一个微妙的点是我们没有明确选择使用哪些零索引。 正确性依赖于只计算物质的事实，因为除了左右分割已经捕获的排序约束之外，零是无法区分的。

 ## 边缘情况

 一个关键的边缘情况是零存在但过于聚集在潜在中间元素的一侧。 考虑：```
0 0 1 0 0
```该算法逐渐分配左零。 当到达中间值1时，左右零池都非空，因此正好形成一个三元组。 消耗后，不可能有更多的三元组，这与最优解匹配，因为只存在一个不同的非零值。 

另一种边缘情况是当出现多个非零值但零不足以支持对称放置时：```
0 1 2 3 0
```这里只能使用中间值之一，因为选择一个后，其余结构不能支持另一个结构的两侧零分配。 贪婪方法确保一旦零被部分消耗，对于后来的候选者，可行性就会正确地降低。 

最后，当零很多但中间重复时：```
0 1 0 1 0 1 0
```仅每个值第一次出现时可用。 这`used_middle`约束确保我们不会错误地重复计算相同的值，即使本地零可用性允许这样做。
