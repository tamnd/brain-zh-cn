 ## 解决方案
 ## 问题理解

 给定一个非递减数组`a`其中每个条目都是一个非负整数。 我们想把这个数组分成一个总和`m`数组`b₁, b₂, ..., bₘ`使得每个`bᵢ`也是非递减的，并且有很强的结构限制：它最多使用`k`独特的价值观。 

在每个位置`j`，所有数组中的值必须精确地加起来`a[j]`。 因此，我们将每个索引的“高度”分布在多个单调序列中，但每个序列本身必须很简单，因为它不能采用太多不同的值。 

任务是找到此类序列的最小数量，或者确定这是不可能的。 

限制很小：`n ≤ 100`,`a[j] ≤ 100`，以及最多 100 个测试用例。 这表明任何解决方案大约`O(n^3)`甚至是细心的`O(n^2 * k)`是可以接受的。 然而，任意分解的强力构造是不可行的，因为可能的数组数量呈指数增长`n`。 

一个关键的结构性限制是每个`bᵢ`是非减的。 这意味着一旦某个值在某个索引上增加，以后就永远不会减少。 结合“至多`k`不同的价值观”，每个`bᵢ`本质上最多由`k`平坦的部分。 

当出现微妙的边缘情况时`a`严格递增且有小间隙。 天真的贪婪分裂可能会低估需要多少“价值层”。 另一个边缘情况是当`k = 1`： 每一个`bᵢ`必须是恒定的，这严重限制了可行性。 

## 方法

 自然的第一次尝试是考虑每一个`bᵢ`作为我们反复剥离的“层”`a`。 由于所有数组都是非递减的，因此每一层也必须是非递减的。 蛮力策略会尝试一层一层地构建：反复找到有效的层`bᵢ`，从中减去它`a`，然后继续。 

这很快就会变得困难，因为选择一层会限制所有未来的层。 每一步都有许多可能的有效分解，探索它们会导致指数分支。 

关键的观察是翻转视角。 我们不构建层，而是推断需要多少层来表示数组中的“跳跃”。 每次该值增加`a`，这种增加必须得到足够多的层的支持，这些层仍然可以适应不同值的变化。 

更具体地说，想象一下扫描`a`从左到右。 每当值从`a[j-1]`到`a[j]`，我们被迫在层中引入足够的容量来支持这种增长，同时保持单调性和限制`k`每层都有不同的值。 每层只能“改变行为”有限次数（最多`k-1`增加）。 这将问题转化为计算有多少单调“增加事件”必须分布在各层上。 

贪心构造变成：模拟跨层分配增量，始终填充现有层，直到它们达到不同值的限制，并且仅在必要时打开新层。 

这导致了最小分层解释：每层最多可以吸收`k-1`值沿着数组增加。 因此，我们将贪婪的增量分组到容量桶中`k-1`，桶的数量就是答案。

 ## 算法演练

 我们处理数组并只关注其中的位置`a[j] > a[j-1]`，因为扁平段不会强制结构发生变化。 

1. 计算所有正增长`d[j] = a[j] - a[j-1]`为了`j ≥ 2`。 每个这样的位置都代表一个必须由层支持的强制性“增加事件”。 
2. 将每个单元的增加视为需要分配到层中，但观察每层最多可容纳`k-1`在需要引入超出其允许限制的新的独特值之前发生此类增加事件。 
3. 维护当前层数`m`以及一个计数器，用于跟踪已分配给当前层批次的增量数量。 
4. 迭代数组并将增加的值累积到当前批次中。 如果添加下一个所需的增量将超出容量`k-1`，开始一个新层并重置计数器。 
5. 如果`k = 1`，立即检查可行性。 在这种情况下，每个`bᵢ`必须是常量，因此唯一可能的数组和来自堆叠常量数组。 这只有在以下情况下才有可能：`a`是常数，否则答案是`-1`。 
6. 输出创建的层总数。 

### 为什么它有效

 每层对应一个最多有一个非递减序列`k`不同的值，这意味着它最多只能从一个值转换到另一个值`k-1`次。 每一次严格的增加`a`迫使层中某处至少支持一个这样的转换。 

由于所有层都独立且累加地贡献，因此将增加事件贪婪地分配到容量受限的存储桶中可以最大限度地减少所需的层数。 任何减少层数的尝试都需要某些层吸收超过`k-1`增加，违反了不同值约束。 相反，贪婪打包总是尊重限制，从不浪费容量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        if k == 1:
            ok = all(x == a[0] for x in a)
            print(1 if ok else -1)
            continue

        increases = 0
        layers = 1
        used = 0

        for i in range(1, n):
            if a[i] > a[i - 1]:
                inc = a[i] - a[i - 1]
                used += inc
                if used > k - 1:
                    layers += 1
                    used = inc

        print(layers)

if __name__ == "__main__":
    solve()
```该解决方案从直接可行性检查开始`k = 1`。 在这种情况下，每个数组都必须是常数，因此任何变化`a`立即使分解不可能。 

为了`k ≥ 2`，代码跟踪有多少“增加单元”被分配到当前图层组中。 每当这个超过`k-1`，创建一个新层。 价值`k-1`出现是因为非递减数组最多有`k`不同的值最多可以增加`k-1`次。 

一个微妙的点是我们积累差异`a[i] - a[i-1]`，而不仅仅是计算位置。 这确保了较大的跳跃按比例消耗更多的容量，因为它们需要在分层分解中增加多个单位。

 ## 边缘情况

 当`k = 1`，算法立即检查所有元素是否相等。 用于输入`a = [5, 5, 5]`，它返回`1`因为单个常量数组就足够了。 用于输入`a = [0, 0, 1]`，它返回`-1`因为没有持续的分解可以产生严格的增加。 

当数组只有一个元素时，例如`n = 1`， 任何`k ≥ 1`有效，答案总是`1`。 该算法自然会处理这个问题，因为没有遇到增加，并且`layers`遗迹`1`。 

当增量较大时，例如`a = [0, 0, 10]`和`k = 3`，算法正确地将跳跃计算为`10`容量单位。 由于每一层只能处理`2`增加，就会产生`5`层，反映出大的跳跃必须分布在多个序列中，而不是被视为单个事件。
