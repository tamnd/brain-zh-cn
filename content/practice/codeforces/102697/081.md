 ## 解决方案
 ## 问题理解

 图书馆藏有书籍，每本书都由两个词描述：作者的姓氏和书籍的类型。 输入以任意顺序给出书籍。 任务是重新组织它们，以便书籍按体裁分组，体裁本身按字母顺序显示，并且每个体裁中作者的姓氏也按字母顺序显示。 每个流派打印一次，后面是其作者，用逗号分隔。 该声明保证流派名称和作者名称均由单个单词组成。 

关键细节是不需要保留书籍的原始顺序。 我们只关心两个独立的字母顺序：体裁名称的顺序和每个体裁内作者的顺序。 这使得这是一个分组和排序问题，而不是图形或动态编程问题。 

发布的声明没有指定书籍数量的数字上限。 它给出了 1 秒的时间限制和 256 MB 的内存，因此实​​现应该避免不必要的重复扫描，并且应该具有标准的排序复杂性。 O(n log n) 解决方案非常适合普通的竞争性编程输入大小，而 O(n²) 方法随着 n 的增长而变得有问题。 例如，对于 100,000 本书，二次方法可以执行大约 5,000,000,000 次成对比较，这远远超出了 1 秒 Python 程序应该尝试的范围。 

微妙的边缘情况是只包含一本书的类型。 例如，```
1
Tolkien fantasy
```产生```
fantasy: Tolkien
```没有逗号，因为只有一位作者。 始终附加的实现`", "`在作者产生错误的尾随分隔符之后。 

另一个边缘情况是输入顺序与所需的输出顺序没有关系。 例如，```
3
Zola history
Asimov science
Adams history
```必须产生```
history: Adams, Zola
science: Asimov
```正确分组但按首次看到的顺序打印流派的解决方案会错误地放置`science`前`history`如果输入碰巧先介绍了它。 

同样的问题也发生在一个流派内部。 例如，```
3
Zola history
Adams history
Brown history
```必须产生```
history: Adams, Brown, Zola
```在读取输入时简单地附加作者会保留混乱的输入顺序，而不是所需的字母顺序。 

## 方法

 一个简单的暴力解决方案可以重复搜索下一个流派，然后搜索所有书籍以找到属于该流派的作者。 可以通过将书籍标记为已处理、选择按字母顺序最小的未处理类型、收集其所有书籍、对这些作者进行排序并重复来使其正确。 问题是重复扫描所有 n 本书可能需要 Θ(n²) 工作。 在最坏的情况下，大约会执行 n² 次比较，对于 n = 100,000，大约需要 100 亿次操作。 

蛮力方法之所以有效，是因为每本书最终都会被分配到一个类型，但它会花时间重新发现在读取输入时已经可用的信息。 有用的观察是，一本书自然地属于由其体裁确定的一组。 我们可以将这些组直接存储在字典中。 分组建立后，我们只需要对流派名称进行排序，并对每个流派的作者列表进行排序。 

不需要更复杂的数据结构。 Python 的字典为每本书提供了预期的 O(1) 插入时间，并且其内置排序为 k 个作者的列表提供了 O(k log k) 时间。 如果流派组包含大小 k₁、k2、...、k_g，则对作者进行排序的总成本为 Σ kᵢ log kᵢ，最多为 O(n log n)。 对 g 个流派名称进行排序的成本为 O(g log g)，也受 O(n log n) 限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 对于大 n 来说太慢 |
 | 使用字典进行分组并排序 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 创建一个字典，其键是流派名称，其值是作者列表。 当一本书有作者时`A`和流派`G`, 追加`A`到关联的列表`G`。 这会在单个输入过程中执行分组，因此我们不必再次扫描整个集合来查找某个流派的书籍。 
2. 从字典中提取所有流派名称并按字母顺序排序。 输出需要对流派本身进行排序，因此直接迭代字典是不够的。 
3. 一次处理一个排序的流派。 对于每种类型，按字母顺序对其作者列表进行排序。 由于属于该类型的所有作者都已经在一起，因此这种排序仅适用于相关子集。 
4. 将已排序的作者加入`", "`并打印流派，然后`": "`。 加入而不是手动添加分隔符可以避免尾随逗号并自动处理单作者情况。 

### 为什么它有效

 不变的是，在读取输入的任何前缀后，该前缀中的每本书在属于其流派的作者列表中只出现一次。 因此，在读取完整的输入后，每种类型都准确包含其书籍的作者，而不包含其他人。 对流派键进行排序会产生所需的流派顺序，对每个相应的作者列表进行排序会产生该流派内所需的作者顺序。 因此，最终输出仅包含每本输入书籍一次，并且满足所需的字母顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    genres = {}

    for _ in range(n):
        author, genre = input().split()
        if genre not in genres:
            genres[genre] = []
        genres[genre].append(author)

    for genre in sorted(genres):
        authors = sorted(genres[genre])
        print(f"{genre}: {', '.join(authors)}")

if __name__ == "__main__":
    solve()
```字典`genres`是算法中描述的分组的直接表示。 成员资格检查会在某个流派第一次出现时创建一个列表，然后后续书籍只需将其作者添加到该列表中即可。 

表达式`sorted(genres)`按字典顺序生成流派名称。 Python 按字典顺序比较字符串，这正是语句所要求的字母顺序。 作者姓名在以下情况下使用相同的顺序：`sorted(genres[genre])`被称为。 

这`join`操作值得关注，因为输出格式化是问题的一部分。 它为三位作者提供了`A, B, C`，而对于一位作者来说，它只产生`A`。 因此，最后一位作者没有特殊情况，也不可能意外打印出额外的逗号。 

不存在整数溢出问题，因为用于控制流的唯一整数是书籍数量，而 Python 整数具有任意精度。 输入循环还对每本书只处理一次。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) | O(n log n) | 分组成本 O(n)，对所有流派名称排序成本 O(g log g)，对所有作者列表排序成本至多 O(n log n) |
 | 空间| O(n) | 每个作者在分组字典中存储一次 |

 这里 n 是书籍的数量，g 是不同类型的数量。 由于 g ≤ n，总运行时间为 O(n log n)。 该解决方案将输入信息存储在字典中，因此其内存消耗是线性的。 在规定的 1 秒时间限制下，避免二次重新扫描是主要的性能要求。

 ## 边缘情况

 单本书的情况由正常的分组和连接逻辑处理。 为了```
1
Tolkien fantasy
```字典变成`{"fantasy": ["Tolkien"]}`。 唯一的流派是`fantasy`，其作者名单仍然存在`["Tolkien"]`排序后，以及`", ".join(...)`回报`Tolkien`。 输出正是`fantasy: Tolkien`。 

具有许多书籍但任意输入顺序的类型也可以在没有特殊逻辑的情况下进行处理。 为了```
4
Zola classics
Young classics
Smith classics
Adams classics
```存储的作者列表最初是`["Zola", "Young", "Smith", "Adams"]`。 排序将其更改为`["Adams", "Smith", "Young", "Zola"]`，并且连接产生`classics: Adams, Smith, Young, Zola`。 仅进行分组而不进行排序的实现会默默地保留错误的顺序。 

以不方便的顺序出现的流派执行了第二个排序要求。 为了```
4
Zed author1
Amy author2
Bob author1
Cal author3
```字典是按照顺序构建的`author1`,`author2`,`author3`，但实现并不依赖于该顺序。 对键进行排序给出了相同的字母顺序，而作者`author1`分别排序自`Zed, Bob`到`Bob, Zed`。 最终结果是```
author1: Bob, Zed
author2: Amy
author3: Cal
```更普遍的教训是，输入顺序永远不应该影响输出的任一级别。 字典只是一个临时的分组结构。 键和值在打印之前都已显式排序，因此无论图书馆的书籍最初如何排列，算法都保持正确。
