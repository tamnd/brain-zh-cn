 ## 解决方案
 ## 问题理解

 输入是一行，其中包含一个序列，例如`3 + 4 * 3 - 6 / 3 * 3`。 每个数字占用一个标记，并且仅由一位数字组成，连续标记之间恰好有一个空格。 第一个和最后一个标记是数字。 

在应用所需的优先规则后，我们需要打印表达式表示的整数。 该语句保证最终答案符合有符号 32 位整数，并且本身也是一个整数。 

语句中的标记数量没有明确的上限。 这使得运行时间随表达式长度呈二次方增长的算法存在不必要的风险。 在一秒的限制下，我们的目标应该是单次通过表达式，其长度是线性的。 每个数字都有一位数字的事实使得标记化特别简单，但它并没有改变有效处理任意长序列的需要。 

有两种边缘情况很容易被误处理。 

考虑：```
3 - 6 * 3
```正确的输出是：```
-15
```一个从左到右的计算器，只需执行它遇到的每个操作即可计算`(3 - 6) * 3 = -9`，这违反了乘法优先级。 

一个更微妙的情况是：```
5 / 2 * 2
```正确的结果是：```
5
```除法和乘法具有相同的优先级，因此必须从左到右计算它们：`(5 / 2) * 2`。 中间值为`5/2`，即使最终答案是一个整数。 使用整数除法的实现将变成`5 / 2`进入`2`并错误地产生`4`。 将当前乘法值保留为精确分数可以避免此问题。 

另一种有用的边界情况是仅包含一个数字的表达式：```
7
```它的答案很简单`7`。 假设始终存在运算符的代码可能会意外访问不存在的令牌或错误地初始化结果。 

## 方法

 直接的方法是重复定位下一个乘法或除法，执行它，用结果替换涉及的三个标记，然后对加法和减法执行相同的操作。 这是正确的，因为它明确遵循优先规则。 如果表达式包含`k`然而，通过剩余表达式的每次搜索都可以检查 O(k) 个标记，并且可以有 O(k) 个这样的搜索。 在最坏的情况下，这大约执行`k + (k - 1) + ... + 1 = k(k + 1)/2`令牌检查，即 O(k²)。 

暴力法之所以有效，是因为优先级结构很简单，但它会重复地重新处理表达式中已经被理解的部分。 关键的观察是，当我们遇到`+`或者`-`，前面的每一个`*`和`/`操作已经解决。 我们可以将未解决的乘法/除法链保留在一个变量中，并在达到加法或减法时将整个链提交到最终总和。 

还有一个额外的细节，因为除法可以产生小数中间结果。 我们应该将当前的乘法/除法链表示为精确的有理数，而不是使用整数除法或浮点数。 蟒蛇的`Fraction`准确地提供了这种表示。 由于最终结果保证是整数，因此我们可以在确认分母为1后打印其分子。 

生成的算法扫描表达式一次，立即执行每个操作，并且不需要重新扫描或重新排列标记。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(k²) | O(k) | 对于长表达式来说太慢 |
 | 最佳 | O(k) | O(k) | 已接受 |

 这里`k`是运算符的数量，相当于表达式中的 θ(k) 个标记。 

## 算法演练

 1. 将输入行拆分为标记。 数字出现在偶数位置，运算符出现在奇数位置，因为输入中每个标记之间恰好包含一个空格。 
2. 初始化`total = 0`和`term`到第一个数字。 变量`term`表示已读取但尚未添加到最终答案中的完整乘法/除法链。 
3. 处理剩余的每个运算符及其紧随其后的数字。 如果操作员是`*`, 乘以`term`按那个数字。 如果是的话`/`, 除`term`使用精确的有理表示来计算该数字。 
4. 当操作者`+`或者`-`，添加当前的`term`到`total`，使用适当的符号，并从下一个数字开始新的术语。 我们可以承诺`term`此时，因为属于它的每个乘法或除法都已被处理。 
5. 处理完最后一个令牌后，添加最后一个令牌`term`到`total`。 没有以下内容`+`或者`-`运算符来触发此操作，因此必须显式完成。 
6. 打印结果整数。 该问题保证最终的数学结果是整数，因此精确分数的分母为 1。 

不变量是在处理加法或减法之前，`term`正是当前最大乘法/除法段的值，而`total`正是所有完成的加法/减法段的值。 由于乘法和除法会立即解决，而加法/减法仅组合已完成的项，因此该算法在每个点都保持所需的优先级。 

## Python 解决方案```python
Pythonimport sysinput = sys.stdin.readline
from fractions import Fraction

def solve():    tokens = input().split()
    total = Fraction(0)    term = Fraction(int(tokens[0]))
    i = 1    while i < len(tokens):        op = tokens[i]        value = int(tokens[i + 1])
        if op == '*':            term *= value        elif op == '/':            term /= value        elif op == '+':            total += term            term = Fraction(value)        else:  # op == '-'            total += term            term = Fraction(-value)
        i += 2
    total += term
    print(total.numerator // total.denominator)

if __name__ == "__main__":
```第一个数字初始化`term`而不是`total`因为必须先完成乘法和除法，然后该值才能参与加法或减法。 

为了`*`和`/`，立即修改当前术语。 这自然会为同等优先级的操作提供从左到右的评估。 例如，`8 / 4 * 3`变成`2 * 3`， 然后`6`，而不是将其解释为`8 / (4 * 3)`。 

为了`+`，将完成的项添加到`total`，下一个数字开始一个新学期。 为了`-`，使用相同的想法，只是新术语以负数开头。 这避免了需要单独的符号变量。`Fraction`是实现的微妙部分。 蟒蛇的`//`将执行整数除法，这不是普通的算术除法，并且`/`对整数产生浮点值。 诸如此类的表达式`5 / 2 * 2`说明为什么两者都不合适。`Fraction`商店`5/2`精确地，然后乘以`2`准确返回`5`。 

输入保证表达式有效，因此不会发生被零除的情况。 Python 整数也具有任意精度，因此即使官方最终结果保证适合 32 位，也不存在溢出问题。

 ## 边缘情况

 单个数字表达式，例如```
7
```开始于`term = 7`，循环没有要处理的运算符，并且最终`total += term`产生`7`。 该算法从不假设运算符存在。 

为了优先考虑，请考虑```
3 - 6 * 3
```该算法开始于`term = 3`。 减法提交`3`到`total`并开始`term = -6`。 然后乘法将该项更改为`-18`。 在最后，`total + term`是`3 - 18 = -15`。 乘法在减法之后永远不会被计算，因此保留了所需的优先级。 

对于同等优先级操作，请考虑```
5 / 2 * 2
```初始项是`5`。 除法将其更改为精确分数`5/2`，乘法将其更改为`5`。 最终输出是`5`。 整数除法实现将获得`2`除法后输出错误`4`。 

最后，考虑负乘法/除法链，例如```
1 - 5 / 2 * 2 + 4
```减法之后，`term`是`-5`。 事业部生产`-5/2`, 乘法产生`-5`，下一个添加提交该术语，给出`1 - 5 = -4`。 下学期开始于`4`给出了最终答案`0`。 精确的有理表示处理负中间值，而不依赖于特定于语言的整数除法规则。
