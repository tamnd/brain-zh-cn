 ## 解决方案
 ## 问题理解

 给定一个正复合整数`n`。 任务是找到最小的除数`n`大于`1`。 

例如，除数`2001`开始于`1, 3, 23, ...`，所以所需的答案是`3`。 官方声明给出了这个例子，并指定输入的数字保证是合数。 

输入仅包含一个整数，因此不需要多个测试用例或任何复杂的输入处理。 官方给出的问题有1秒的时间限制和256MB的内存限制。 该语句没有公开明确的上限`n`，因此自然的方法是避免不必要的工作，并在找到除数后立即停止。 

关键的数学事实是，如果`n`是复合的，它有一个因子`d`和`2 <= d <= sqrt(n)`。 如果该范围内没有整数可以整除`n`， 然后`n`将是主要的。 由于输入保证`n`是复合的，搜索到`sqrt(n)`就足够了。 

一种边缘情况是最小除数是`2`。 用于输入`8`，正确的输出是`2`。 开始检查的实现`3`会错误地返回`4`或者可能完全失败。```
Python8
```正确的输出是：```
Python2
```另一个边缘情况是完美的正方形。 用于输入`49`，最小的除数是`7`， 和`7 * 7 = 49`。 在检查之前停止的循环`sqrt(n)`会错过答案。```
Python49
```正确的输出是：```
Python7
```第三个有用的边界情况是最小可能的复合输入，`4`。```
Python4
```答案是`2`。 该算法必须包括`2`在其搜索中并且必须允许除数等于`sqrt(n)`。 

## 方法

 直接的暴力方法是尝试来自`2`通过`n - 1`并返回第一个除法`n`。 它是正确的，因为每个可能的答案都是按升序检查的，因此第一个成功的除数必然是最小的除数。 问题是，对于一个大合数，其最小除数接近于`n / 2`，这大致执行`n / 2`模运算。 更糟糕的是，如果输入范围很大，线性扫描将花费大部分时间来检查不可能是最小因子的数字。 

因子对的结构为我们提供了更好的停止点。 如果`n = a * b`并且两个因素都大于`sqrt(n)`，他们的乘积将大于`n`，这是不可能的。 因此，每个合数至少有一个不大于`sqrt(n)`。 我们只需要搜索该范围即可。 

对于这个问题还有一个更简单的观察。 我们正在寻找最小的除数，因此我们可以从以下位置开始按升序测试候选者`2`。 第一个成功的候选者就是答案，如果前面没有遇到答案，我们只需要继续通过`sqrt(n)`。 对于复合输入，循环保证最迟在此处终止。 

因此，优化方法减少了线性输入中最坏情况下的整除性检查次数。`n`线性于`sqrt(n)`。

 | 蛮力 | O(n) | O(1) | O(1) | 对于大 n 来说太慢 |
 | 最佳| O(sqrt(n)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取复合整数`n`。 
2. 启动候选除数`2`。 这是大于的最小可能正除数`1`，所以必须先进行测试。 
3. 按升序测试候选人，同时`candidate * candidate <= n`。 如果`n % candidate == 0`， 打印`candidate`并停止。 因为候选者是按升序检查的，所以找到的第一个除数是最小的。 
4. 循环必须始终为所承诺的复合输入找到除数。 如果没有，`n`没有除数`2`通过`sqrt(n)`，这意味着`n`是素数。 

条件`candidate * candidate <= n`优于计算浮点平方根。 它避免了浮点精度问题并直接表达数学边界。 

### 为什么它有效

 不变的是在测试候选人之前`d`，每个整数`2`通过`d - 1`已检查且不划分`n`。 因此，当`d`划分`n`，不存在更小的有效除数，所以`d`正是所需的答案。 合数最多只能有一个除数`sqrt(n)`，因此搜索无法在没有找到答案的情况下通过平方根边界。 

## Python 解决方案```python
Pythonimport sysinput = sys.stdin.readline
def solve():    n = int(input())
    d = 2    while d * d <= n:        if n % d == 0:            print(d)            return        d += 1
if __name__ == "__main__":    solve()
```程序读取唯一的输入值并初始化`d`到`2`，匹配我们允许输出的最小除数。 

循环使用`d * d <= n`而不是`d <= int(sqrt(n))`。 乘法完全保留在整数运算中，因此在完美平方处不存在舍入问题，例如`49`。 

什么时候`n % d == 0`，当前候选人划分`n`。 由于所有较小的候选人都已经失败，打印`d`立即给出正确答案并避免不必要的工作。 

输入保证是复合的，因此基本情况不需要输出。 如果问题确实允许素数输入，则算法将需要在循环后进行额外的决策。 在这里，这种情况不可能发生。

 ## 边缘情况

 对于`n = 4`，算法开始于`d = 2`。 条件`2 * 2 <= 4`是真的，并且`4 % 2 == 0`，所以它立即打印`2`。 这处理尽可能小的合数，没有任何特殊情况。 

为了`n = 8`，第一个候选者又是`2`， 和`8 % 2 == 0`。 答案会打印在考生之前，例如`3`或者`4`被考虑。 这就是为什么搜索必须从`2`，而不是在`3`。 

为了`n = 49`, 候选人`2`通过`6`失败。 什么时候`d`达到`7`，循环条件仍然为真，因为`7 * 7 == 49`。 整除性测试成功并且程序打印`7`。 使用`d * d < n`相反会默默地产生错误的结果。 

为了`n = 2001`,`2`失败并且`3`成功，因此程序打印`3`。 该算法不需要考虑剩余值`667`，因为该问题仅要求最小的非单位除数。
