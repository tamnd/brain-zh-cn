 ## 解决方案
 ## 问题理解

 该任务正好有三种食物选择：一块牛排贡献 500 卡路里，一个苹果贡献 100 卡路里，一块面包贡献 50 卡路里。 给定一个目标`n`，保证能被 50 整除，我们需要精确消费`n`卡路里，同时使用尽可能少的单个食物。 输出要求该最小项目解决方案中牛排、苹果和面包的数量（按顺序）。 

关键限制是每个卡路里值都是 50 的倍数。将整个问题除以 50 将三种食物值变为`10`,`2`， 和`1`。 这使得结构特别简单：一块牛排代替了五个苹果或十个面包，因此只要可以使用牛排而不会使剩余的热量无法形成，使用它只能减少食物的数量。 

该声明没有给出明确的上限`n`在问题页面上，因此算法应该避免与`n`，尤其是嵌套枚举。 恒定时间算术解决方案更可取，并且可以轻松满足一秒时间限制和 256 MB 内存限制。 

第一个边缘情况就是一个面包。 用于输入`50`，唯一可能的解决方案是`0`牛排,`0`苹果，和`1`面包，所以输出是`Steak: 0`,`Apples: 0`,`Bread: 1`。 假设至少可以使用一块牛排或苹果的实现在这里将会失败。 

第二个边缘情况是目标对于牛排来说不够大，但可以被苹果整除。 用于输入`200`，正确的输出是`Steak: 0`,`Apples: 2`,`Bread: 0`。 一个总是尝试先保留一块牛排的粗心实现将无法使用一块牛排，但正确的方法只是简单地获取零块牛排并用苹果处理剩余的牛排。 

第三个有用的边界情况是牛排上方的目标。 用于输入`550`，正确的输出是`Steak: 1`,`Apples: 0`,`Bread: 1`。 吃完牛排后，剩下的50卡路里必须变成一份面包。 忘记最后的余数会产生不完整的解决方案。 

最后，对于 500 的精确倍数，例如`2500`，答案是`5`牛排和其他一切都是零。 输出格式需要所有三个计数，包括零计数，而不是省略未使用的食物。 官方示例演示了这种行为`2500`。 

## 方法

 直接的暴力解决方案可以尝试所有可能数量的牛排，然后尝试所有可能数量的苹果，并检查剩余的卡路里是否可以由面包提供。 对于每对计数，都会确定总卡路里，因此此方法是正确的，因为它最终会检查每种可能的组合。 如果`n`然而，候选对的数量却呈二次方增长。 将卡路里乘以 50 后，可能的牛排数量约为`n / 500`，对于每个牛排数量，大约可以有`n / 100`苹果数数，大致给出`n² / 50000`最坏情况下的组合。 精确的常数很小，但二次相关性是不必要的。 

蛮力之所以有效，是因为它明确地搜索了整个可行空间，但宗派的结构给了我们更强大的东西。 一块牛排所含的热量是一个苹果的五倍，是面包的十倍。 由于每个目标都可以被 50 整除，因此在选择尽可能多的牛排后，剩余的数量始终是 50 的倍数，因此始终可以用苹果和面包来表示。 在这两种食物中，苹果的热量是面包的两倍，所以我们应该尽可能多地使用苹果。 剩余的数量要么是零，要么正好是 50，这需要面包。 

这给出了仅具有整数除法和余数的贪婪解决方案。 我们采取`n // 500`牛排，除去其中的卡路里，从剩余的部分中取出尽可能多的苹果，然后将最后剩下的 50 卡路里用作面包。

 | 蛮力 | O(n²) | O(1) | O(1) | 对于大 n 来说太慢 |
 | 最优贪心 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取目标卡路里数`n`。 自从`n`能被 50 整除，去掉 500 卡路里的牛排所产生的余数也能被 50 整除。 
2. 计算`steaks = n // 500`。 这是牛排的最大数量。 使用更少的牛排会用几种较小的食物替代至少一种 500 卡路里的食物，因此永远无法提高最低食物数量。 
3.减去牛排的卡路里`n`。 剩余卡路里现在严格低于 500。 
4. 计算`apples = remainder // 100`。 这是剩余卡路里中所能容纳的最大数量的苹果。 由于苹果是仅次于牛排的第二大食物，用面包代替苹果只能增加食物的数量。 
5. 从余数中减去苹果的热量。 因为余数是 50 的倍数，现在小于 100，所以剩下的唯一可能值是 0 或 50。 
6. 计算`bread = remainder // 50`。 这会产生零个或一个面包，正好覆盖剩余的卡路里。 
7. 使用所需标签打印三个计数。 

### 为什么它有效

 不变的是，在每次贪婪的选择之后，剩余的卡路里仍然可以由较小的食物大小精确地表示。 吃尽可能多的牛排是安全的，因为每块牛排都具有最大的卡路里值，因此用较小的食物代替一份牛排需要至少两件额外的食物。 一旦牛排数量确定，同样的论点也适用于苹果与面包。 由于最终余数保证为 0 或 50，因此面包完成了确切的目标。 因此，贪心构造是可行的，并且每个决策都最大化使用最大的可用食物，从而最小化项目总数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    steaks = n // 500
    n %= 500

    apples = n // 100
    n %= 100

    bread = n // 50

    print(f"Steak: {steaks}")
    print(f"Apples: {apples}")
    print(f"Bread: {bread}")

if __name__ == "__main__":
    solve()
```第一个除法计算牛排的最大可能数量。 使用整数除法而不是循环使该操作的时间恒定。 

剩余操作员立即去除牛排所含的卡路里。 此时剩余值低于 500。然后将相同的模式应用于苹果，留下低于 100 的值。 

因为原始目标能被 50 整除，所以最后的余数也必须能被 50 整除。由于它低于 100，所以只能是 0 或 50，所以整数除以 50 正好给出了所需的面包数。 

解决方案中的任何地方都没有浮点运算。 这避免了舍入问题，也使整除性论证变得精确。 Python 整数具有任意精度，因此即使目标大于通常的 32 位范围，也不存在整数溢出问题。 

操作顺序很重要。 我们必须先去掉牛排，然后去掉苹果，因为贪婪证明取决于将食物从最大卡路里值加工到最小卡路里值。

 ## 边缘情况

 对于`50`，算法首先计算`50 // 500 = 0`，所以没有选择牛排。 其余部分保持 50，并且`50 // 100 = 0`，所以也没有选择苹果。 最后，`50 // 50 = 1`，生产`Steak: 0`,`Apples: 0`,`Bread: 1`。 这证实了在没有特殊情况的情况下处理最小的合法目标。 

为了`200`，牛排数量为`200 // 500 = 0`。 剩下的200卡路里产生`200 // 100 = 2`苹果，留下零卡路里。 最终的面包数量为零，给出`Steak: 0`,`Apples: 2`,`Bread: 0`。 该算法永远不需要强迫最大的食物出现。 

为了`550`，牛排数量为`550 // 500 = 1`，剩下 50。50 中没有苹果，因此苹果数为零。 剩下的 50 个恰好变成了一个面包。 结果是`Steak: 1`,`Apples: 0`,`Bread: 1`，总共有两种食物。 

为了`2500`，第一部分给出`2500 // 500 = 5`并且余数变为零。 随后的两个除法也产生零。 输出是`Steak: 5`,`Apples: 0`,`Bread: 0`，这确认了零值类别仍然必须打印，并且最大面额的精确倍数不需要更小的食物。 

对于非常大的目标，例如`1000000000`，该算法执行与小输入相同的三个划分阶段。 它获得了两百万块牛排，剩余为零。 循环不随目标增长，这是算术贪心解决方案的主要优点。
