 ## 解决方案
 ## 问题理解

 我们会按照访问的顺序获得骑自行车期间访问过的点的海拔高度。 连续的海拔形成单独的骑行段。 山是一个最大的连续延伸，其中每个部分都严格向上。 它的垂直高度就是该延伸段末端的高度减去其开始处的高度。 

任务是找到最大的垂直上升。 下坡路段或平坦路段会中断当前的上坡路段，因此下一个增加的路段将开始新的候选山坡。 该声明保证至少存在一个严格上坡的路段。 

官方问题页面没有指定上限`n`或高程值。 它给出了 1 秒的时间限制和 256 MB 的内存限制。 由于所需的计算可以通过一次高程完成，因此`O(n)`算法是自然目标，即使在以下情况下也是安全的：`n`非常大。 二次算法一旦出现问题就会出现问题`n`达到通常的竞争性编程规模`10^5`，其中大致`5 * 10^9`必须考虑对。 

有几种边缘情况可能会导致实施出现微妙的错误。 平坦的路段必须终止于山丘。 例如，```
8
100 200 300 300 400 500 600 700
```有答案`400`， 不是`600`。 第一次升起自`100`到`300`是一座山，平等`300`价值观打破了它，第二座山从那里升起`300`到`700`。 将非递减序列视为上坡的粗心实现会错误地组合两部分并返回`600`。 这也是第三个正式样品。 

下坡路段也终止了当前的山坡。 例如，```
7
600 650 700 690 740 520 600
```有答案`100`。 第一座山从`600`到`700`, 给予`100`， 尽管`690`到`740`给出`50`和`520`到`600`给出`80`。 在下坡步骤后不断累积的实现可能会错误地组合不相关的爬坡。 

山坡可以恰好在最终海拔处结束，因此即使没有后续的下坡或平坦路段，也必须检查最后的增量运行。 例如，```
5
100 150 120 300 500
```有答案`380`， 从`120`到`500`。 仅在遇到中断时更新答案的实现将错过最后的山峰并可能返回`50`。 

最小的有效输入必须包含至少两个点，因为该语句保证了正的上坡部分。 例如，```
2
10 20
```有答案`10`。 单个可用段本身就是一座完整的山。 

## 方法

 直接暴力解决方案考虑了每一个可能的起点，并在海拔继续增加的同时延伸山丘。 每当下一个海拔不严格更大时，该候选山就会停止。 由于有效上坡路段的海拔高度完全由其第一个和最后一个海拔决定，因此这种方法是正确的：检查每个可能的山坡，并将其海拔高度与当前最大值进行比较。 

问题是这些候选人中有许多是重叠的。 在长度严格递增的数组上`n`，从第一点开始大致导致`n - 1`扩展，从第二个原因开始`n - 2`， 等等。 扩展总数为`(n - 1) + (n - 2) + ... + 1 = n(n - 1)/2`。 

因此最坏的情况是`O(n^2)`。 为了`n = 100000`，这是关于`4,999,950,000`扩展，远远超出 1 秒解决方案可以处理的范围。 

有用的观察是，上坡并不需要我们记住每一次中间的上升。 假设当前山丘的起始高度为`start`，我们目前处于海拔高度`h`。 只要下一个海拔更大，整个序列仍然是一个有效的山，并且它的上升很简单`h - start`。 当下一个值不大于时，山就结束了。 然后，我们可以丢弃其所有内部点，并在新的标高处开始下一个候选点。 

这将问题转化为单次扫描。 我们保持当前严格增加运行的起始海拔，并将每个新海拔与前一个海拔进行比较。 当新值较大时，当前山体的海拔高度为`current - start`。 当它不更大时，当前运行结束，新点成为下一个可能的山坡的起点。 

蛮力之所以有效，是因为它明确地探索了每次增加的运行，但由于重复检查相同的前缀而失败。 观察到增加的运行只能通过其起始高度和当前端点来表示，这让我们可以对每个相邻对恰好处理一次。

 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最佳| O(n) | O(1) 辅助 | 已接受 |

 ## 算法演练

 1. 读取高程点数和高程数组。 我们只需要之前的海拔、当前上坡的起始海拔以及迄今为止找到的最佳坡度。 
2. 设置`start`到第一个标高并且`prev`到第一个标高。 开始时，当前的山不包含任何线段，因此其上升为零。 
3. 从左到右扫描剩余的高程。 对于每个`cur`，将其与`prev`。 
4. 如果`cur > prev`，骑行继续严格上坡。 保持相同`start`，因为自此以来每个增加的部分`start`属于同一座山。 目前的涨幅为`cur - start`，因此如果该值较大，则更新最大值。 
5.如果`cur <= prev`，当前的山已经结束。 就像下坡路段一样，平等也算作休息，因为定义要求每个路段都严格是上坡路段。 放`start = cur`这样一座新的山就可以从此时开始。 
6. 设置`prev = cur`并继续扫描。 最终的最大值就是答案。 

### 为什么它有效

 不变量是在处理每个新高程之前，`start`是已处理数组的当前最大严格递增后缀的第一个标高。 如果下一个高程大于`prev`，该后缀仍然严格递增，所以它的上升恰好是`cur - start`。 如果下一个高程不更大，则没有有效的上坡部分可以跨越该边界，因此当前后缀必须结束，并且新点是其后面的山唯一可能的起点。 由于每个有效的山丘恰好是一个最大严格递增运行，因此对每个候选者进行评估并保留最大的上升。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    start = a[0]
    prev = a[0]
    best = 0

    for cur in a[1:]:
        if cur > prev:
            best = max(best, cur - start)
        else:
            start = cur

        prev = cur

    print(best)

if __name__ == "__main__":
    solve()
```前两个变量，`start`和`prev`，表示描述当前山所需的两个端点。`start`当海拔严格增加时不会改变，因为每个新点仍然属于同一座山。 

严格比较`cur > prev`是中心细节。 使用`cur >= prev`会错误地允许平坦部分保留在山内。 官方的第三个示例对于检测此错误特别有用。 

当发生中断时，`start`已分配`cur`，而不是`prev`。 这使得下一段能够从当前点开始形成一座小山。 例如，在`100 150 120 300`，新山开始于`120`，不在`150`。 

每当发现增加的段时，答案就会立即更新。 这会处理到达数组末尾的山丘，其中没有后续值可以触发重置。 不需要特殊的后处理。 

Python 整数具有任意精度，因此海拔差异不会带来整数溢出的风险。
