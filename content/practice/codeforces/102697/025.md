 ## 解决方案
 ## 问题理解

 我们得到了一个拼写错误的单词`s`和候选词词典。 拼写错误具有特定的结构：字母可能已被其他字母替换，但没有插入或删除字母。 这意味着目标单词的长度必须与`s`。 在该长度的所有候选词中，我们需要不同于`s`在最少的位置。 如果多个候选者具有相同的最小不匹配数，则输入字典中最早出现的候选者获胜。 官方声明保证至少一名候选人达到所需的长度。 

对于两个长度相等的单词，它们的距离只是它们字符不同的索引数。 例如，比较`deat`和`beat`，只有第一个字符不同，所以距离是`1`。 比较`deat`和`deer`，第三个和第四个字符不同，给出距离`2`。 

存档的问题有 1 秒的时间限制和 256 MB 的内存限制，但该声明没有发布单词长度或字典大小的数字上限。 这使得预期的复杂性特别清晰：我们应该避免单词长度的二次方。 单次比较应该花费单词长度的线性时间，并且处理字典应该花费检查的字符总数的线性时间。 

在一些小情况下，实现可能会默默地选择错误的答案。 如果拼写错误的单词本身出现在字典中，则其距离为零，必须选择它。 例如，```
abc
3
xbc
abc
abd
```正确的输出是`abc`。 将其最佳距离初始化为零或更新的实现`<=`不保留第一次出现可能会错误地处理选择逻辑。 

第二种情况是平局。 考虑，```
deat
3
beat
meat
feet
```两个都`beat`和`meat`不同于`deat`恰好在一个位置，同时`feet`有两点不同。 正确的输出是`beat`，因为它首先出现。 随时更新答案`distance <= best_distance`会错误地替换`beat`和`meat`。 

第三种情况涉及候选人长度错误：```
abc
3
ab
abd
xbc
```正确的输出是`xbc`。 这个词`ab`不能是预期的单词，因为原始错误模型只允许替换，所以它的长度不能改变。 使用一般编辑距离的粗心实现可能会为`ab`并意外地选择了它。 

## 方法

 自然的第一个尝试是将拼写错误的单词与每个字典单词进行比较，并计算有多少位置不同。 这已经是正确的基本策略了。 对于每个候选者，我们将其字符与`s`，计算不匹配项，并保留计数最少的候选项。 具有不同长度的候选者可以立即被忽略。 

如果拼写错误的单词有长度`L`并且有`n`字典条目，最坏情况检查`nL`字符对。 更准确地说，如果每个候选者都具有相同的长度并且没有比较可以提前终止，则该算法将准确执行`nL`人物比较。 由于该语句没有给出明确的上限，因此这是该问题的适当的最坏情况表达式。 

诱人的替代方案是计算一般字符串编辑距离，例如编辑距离。 这将允许插入和删除，但输入模型明确禁止这些操作。 一般的动态编程编辑距离需要`O(L^2)`每个候选人的时间，给予`O(nL^2)`总的来说，这解决了一个比必要的更普遍的问题。 

关键的观察是唯一允许的错误是替换。 一旦两个单词的长度相等，就不需要做出对齐决定。 位置`i`一句话必须直接对应位置`i`换句话说。 因此，它们的距离只是汉明距离，可以通过一次线性扫描来计算。 

蛮力想法之所以有效，是因为每个候选都可以独立检查，但一般的编辑距离实现会做不必要的工作，因为它考虑了不可能发生的插入和删除。 通过观察位置是固定的，我们可以减少与直接逐字符扫描的每次比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 一般编辑距离| O(nL²) | O(L) | 不必要的缓慢 |
 | 直接错配计数 | O(nL) | 除了输入字符串之外，O(1) | 已接受 |

 ## 算法演练

 1.读出拼写错误的单词`s`和它的长度`L`。 长度很有用，因为只有候选人完全符合`L`字符可能是有效的。 
2. 按照给定的顺序阅读每个词典单词。 如果它的长度不是`L`，跳过它。 这样的词是无法从`s`单独使用替换。 
3. 对于长度足够的候选人`L`，扫描所有位置`0`通过`L - 1`并计算有多少个字符与`s`。 这个计数正是所需的距离，因为每个位置都被迫匹配相应的位置。 
4. 保留目前为止看到的距离最小的第一个候选者。 比较应严格`<`， 不是`<=`。 如果新距离等于当前最佳距离，则较早的字典条目必须仍然是答案。 
5. 处理完所有候选词后，打印存储的最佳单词。 保证至少一个字典单词具有相同的长度意味着答案总是存在。 

### 为什么它有效

 不变量是在处理完第一个之后`k`字典条目，`best_word`是那些具有最小替换距离的条目中最早的单词`s`。 每个有效候选者的长度与`s`，所以它的距离正是扫描计算出的不匹配位置的数量。 当候选者的距离严格较小时，替换当前答案可以保留不变量。 当其距离相等时，保持当前答案不变可以保留最早出现的要求。 在处理完每个字典条目后，不变量覆盖整个字典，因此存储的单词正是所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = int(input())

    length = len(s)
    best_word = None
    best_dist = length + 1

    for _ in range(n):
        word = input().strip()

        if len(word) != length:
            continue

        dist = 0
        for a, b in zip(s, word):
            if a != b:
                dist += 1

        if dist < best_dist:
            best_dist = dist
            best_word = word

    print(best_word)

if __name__ == "__main__":
    solve()
```前两次读取获取拼写错误的单词和字典条目数。 我们将其长度存储一次，因为每个候选者都必须具有完全相同的长度。 

长度检查发生在字符比较之前。 这在逻辑上是必要的，而且比尝试比较不兼容的单词要便宜一些。 由于替换无法改变长度，因此此类候选者永远无法成为答案。 

对于每个候选者，不匹配计数器从零开始。`zip(s, word)`将字符配对在相同的位置，这正是仅替换错误模型所强加的对应关系。 不需要动态编程或任何其他对齐机制。`best_dist`开始于`length + 1`，一个大于每个可能的有效距离的值。 这避免了第一个有效候选者需要特殊情况。 一旦候选者的距离较小，它就成为当前答案。 

更新使用`dist < best_dist`。 使用`<=`将通过用同等质量的较晚候选者替换较早的候选者来打破字典顺序平局规则。 

Python整数不会溢出，最大可能的距离只是字长。 除了当前正在读取的字符串之外，该算法还仅使用恒定的辅助空间。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(nL) | 最多`L`对每个进行字符比较`n`候选人。 |
 | 空间| O(1) 辅助 | 仅存储当前候选、答案和恒定数量的计数器。 |

 由于为存档问题发布的约束包括一秒时间限制和 256 MB 内存限制，因此对字典的线性扫描是自然的目标。 该声明没有提供明确的界限`n`或者`L`， 所以`O(nL)`是有意义的复杂性保证，而不是数字操作估计。 

也不需要存储整个字典。 处理每个单词会立即保持辅助内存不变，而 Python 的输入机制则处理各个字符串。

## 边缘情况

 精确匹配的距离为零。 为了```
abc
3
xbc
abc
abd
```第一个候选者的距离为 1，第二个候选者的距离为 0，第三个候选者的距离为 1。 该算法取代`xbc`和`abc`当它遇到零距离候选者并且之后不再替换它时。 输出是`abc`。 

平局必须保留字典中的第一个出现。 为了```
abc
3
xbc
ayc
abz
```每个候选人都不同`abc`恰好在一个位置。 第一个候选者将最佳距离确定为 1。 另外两个距离相等，所以严格`<`比较叶`xbc`不变。 输出是`xbc`。 

长度不同的候选者即使看起来很接近也是无效的。 为了```
abc
4
ab
abcd
xbc
abcde
```仅有的`xbc`长度为三。 该算法在进行任何字符比较之前会跳过其他三个单词，留下`xbc`作为唯一可能的答案。 

所提供示例的一个微妙问题不是算法边缘情况，而是语句不一致。 为了```
deat
6
fate
feet
beat
meat
deer
dean
```显示的定义给出距离一`fate`,`beat`,`meat`， 和`dean`，所以字典顺序平局打破给出`fate`。 尽管如此，存档页面仍会显示`beat`作为输出。 严格从可见定义导出的解决方案应该产生`fate`; 繁殖`beat`需要提供的语句中缺少的附加规则。
