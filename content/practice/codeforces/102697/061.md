 ## 问题理解

 指南针可分为十六个主方向和中间方向。 四个基本方向是北、东、南、西，四个对角方向是东北、东南、西南和西北。 其余八个方向位于相邻方向的中间。 这些是半风，例如 NNE 代表东北偏北，ESE 代表东南偏东。 

输入恰好是一个三字符首字母缩略词，命名这八个半风之一。 任务只是将该首字母缩略词扩展为其小写英文名称，并在两个单词之间使用连字符。 例如，`ESE`变成`east-southeast`。 

这里没有大的数字输入。 输入大小固定为三个字符，因此即使检查每个可能方向的方法实际上也是恒定时间。 一秒的时间限制和 256 MB 的内存限制对于任何直接实现来说都绰绰有余。 主要关注的是正确性而不是渐近性能。 

八个有效的缩写词是`NNE`,`ENE`,`ESE`,`SSE`,`SSW`,`WSW`,`WNW`， 和`NNW`。 由于输入保证是这些有效的半风之一，因此无需处理格式错误的字符串。 

常见的边界情况是`NNW`。 它坐落在`NW`和`N`，所以它的名字是`north-northwest`。 尝试通过将罗盘方向视为简单线性序列来生成名称的实现可能会意外地错误处理从`NW`回到`N`。 

另一个容易犯的错误是颠倒名称的两个部分。 例如，`ENE`是`east-northeast`， 不是`northeast-east`。 缩写词的第一个字母标识了英文名称中首先出现的基本方向。 

字母重复也很正常。 例如，输入`NNE`包含两个`N`字符并且必须产生`north-northeast`。 假设三个字符必须全部不同的实现将错误地拒绝此有效方向。 

## 方法

 最直接的暴力解决方案存储八个可能的缩写词及其对应的名称，然后一一检查，直到输入匹配。 由于只有八种可能性，最坏的情况会执行八次比较才能找到答案。 这已经是常数时间，即使使用最简单的实现也不存在实际的性能问题。 

更简洁的方法是使用字典将每个缩写词直接映射到其全名。 输入本身就是关键，因此可以立即检索答案，而无需显式遍历八种可能性。 有用的观察是该问题有一组封闭的、固定的有效翻译。 无需执行计算，也无需在运行时推断模式，因此直接查找可以准确表达问题。 

暴力方法之所以有效，是因为输入域仅包含八个值，但查找表更容易验证和维护。 也避免了对西北和北部循环边界的特殊处理。

 ## 算法演练

 1. 从标准输入中读取三字符缩写。 删除周围的空格就足够了，因为输入仅包含首字母缩略词。 
2. 将八个有效的缩写词到名称的翻译存储在字典中。 每个键都是一个可能的半风，其值正是所需的小写输出。 
3. 使用输入的缩写作为字典键并打印关联的全名。 由于保证输入有效，因此不需要处理丢失键的情况。 

### 为什么它有效

 该词典仅包含每个有效半风的一个条目，并且每个条目将首字母缩略词映射到其所需的英文名称。 输入保证是这八个首字母缩略词之一，因此查找始终选择唯一的正确翻译。 不需要几何计算或解释，因为指南针命名已经完全由固定映射表示。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    direction = input().strip()

    names = {
        "NNE": "north-northeast",
        "ENE": "east-northeast",
        "ESE": "east-southeast",
        "SSE": "south-southeast",
        "SSW": "south-southwest",
        "WSW": "west-southwest",
        "WNW": "west-northwest",
        "NNW": "north-northwest",
    }

    print(names[direction])

if __name__ == "__main__":
    solve()
```第一行`solve`读取缩写词并使用`strip()`因此标准输入中的尾随换行符不会成为字典键的一部分。 

这`names`字典是完整的翻译表。 拼写和连字符完全按照输出格式的要求存储，这避免了动态构造字符串并消除了一些可能的命名错误。 

最终查找使用`names[direction]`。 由于每个合法输入都显示为键，因此对于有效的测试用例，此操作不会失败。 Python 字典提供平均恒定时间查找。 

没有整数计算，因此整数溢出是无关紧要的。 也没有数组索引或范围，因此没有需要管理的数值相差一边界。

 ## 边缘情况

 的`NNW`边界由显式字典条目处理。 对于输入```
NNW
```查找发现`north-northwest`，这是西北和北之间的方向。 简单地向前遍历方向的线性列表的生成解决方案可能会意外地错过这种环绕情况，而查找表则没有这种依赖性。 

处理重复字符的情况时没有任何逐个字符的假设。 为了```
NNE
```三字符字符串用作一个键，产生```
north-northeast
```事实是`N`出现两次与查找无关。 同样的推理也适用于`ENE`,`SSE`， 和`WNW`。 

最小和最大输入大小一致，因为每个合法输入恰好包含三个字符。 输入如```
ESE
```已经具有最小和最大有效长度。 无论提供八个合法缩写词中的哪一个，该算法都会执行一次字典查找。 

完全相同的缩写，例如```
NNN
```在问题的输入保证下不是有效的测试用例。 它不代表八个半风之一，因此故意不要求解为其分配结果。 这比为问题不允许的输入发明输出更好。
