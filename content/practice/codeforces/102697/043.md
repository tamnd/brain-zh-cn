 ## 解决方案
 ## 问题理解

 我们有直飞网络。 每趟航班从一个城市飞往另一个城市，都有价格。 团队开始于`Syracuse`，必须到达比赛城市，然后必须返回`Syracuse`。 完整往返的总费用不能超过给定的预算。 在所有可行的往返行程中，我们想要总价最低的往返行程，并且必须打印实际的航班顺序。 

官方说法给出了1秒的时间限制和256MB的内存。 它没有发布航班数量或预算的明确数字上限，因此安全的解释是应该使用标准的近线性最短路径算法来处理该图，而不是任何依赖于预算大小的算法。 

该图是有向的，这很重要，因为从`A`到`B`并不意味着航班从`B`到`A`存在。 价格附加在有向边上，因此必须分别考虑到达目的地最便宜的方式和返回最便宜的方式。 

第一种边缘情况是当一个方向不可能时。 例如：```
NewYork
3 10
Syracuse Detroit 9
Detroit NewYork 1
NewYork Syracuse 2
```最便宜的到达方式`NewYork`成本 10，但返回成本另外 2，因此完整行程成本 12。正确的输出是：```
IMPOSSIBLE
```粗心的实施仅检查到达竞争的成本会错误地接受这条路线。 

预算边界也很重要。 考虑：```
B
3 5
Syracuse A 2
A B 1
B Syracuse 2
```唯一的往返成本恰好为 5，因此它是有效的，正确的第一条输出行是：```
4 5
```比较必须是`cost <= budget`， 不是`cost < budget`。 

另一个常见的错误是假设如果有直飞航班就必须使用。 考虑：```
B
5 5
Syracuse B 5
Syracuse A 1
A B 1
B A 1
A Syracuse 1
```直达航班至`B`花费5，但使用它的完整行程花费超出了预算。 比较便宜的往返是`Syracuse -> A -> B -> A -> Syracuse`，成本 4。最短路径算法自然会发现这条多航班路线。 

最后，多个航班可以连接同一对城市。 例如，如果两者`Syracuse -> A`价格 10 和`Syracuse -> A`由于价格 3 存在，只有更便宜的优势对于最低价格路线才重要。 实现应该保留两条边，而不是意外地覆盖其中之一。 

## 方法

 蛮力方法是枚举可能的路线`Syracuse`到比赛城市，枚举可能返回的路线，将每一对组合起来，保留价格符合预算的最便宜的组合。 这是正确的，因为每个可行的行程都被明确考虑。 问题是路线的数量。 即使我们避免循环，有向图也可以包含阶乘许多简单路径。 对于(V)个城市，两个固定城市之间的简单路径数量可以达到

 [
 \sum_{k=0}^{V-2} P(V-2,k),
 ]

 即 (\Theta(V!))。 计算每条路线的价格会增加另一个与其长度成比例的因素。 由于 (V) 本身可能与输入航班的数量成正比，穷举搜索很快就会变得不可用。 

暴力破解之所以有效，是因为每条可能的路线都会被检查，但当图表包含许多替代路径时，暴力破解就会失败。 关键的观察结果是，目标是可加的：一条航线的价格恰好是其航班价格的总和。 所有航班价格都是非负的，因此两个城市之间最便宜的航线是一个普通的加权最短路径问题。 

还有一个更简单的分解。 每个有效的往返行程都包含两条独立的路径，其中一条来自`Syracuse`前往比赛城市和从比赛城市返回`Syracuse`。 如果第一条路径具有最小可能成本 (A)，第二条路径具有最小可能成本 (B)，则每次往返成本至少为 (A+B)。 采取这两条最短路径正好达到(A+B)，因此通过解决两个最短路径问题获得全局最便宜的往返行程。 

我们可以在两个方向上使用 Dijkstra 算法，因为所有边权重都是非负的。 我们还为每个松弛顶点存储一个前身，这使我们可以在找到最小成本后重建实际的飞行序列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (\Theta(V!)) 在最坏的情况下 | (O(V+E)) 加上路线存储 | 太慢了 |
 | 最佳 | (O((V+E)\log V)) | (O(V+E)) | 已接受 |

 ## 算法演练

 1.了解比赛城市、航班数量、可用预算。 构建包含每个航班及其价格的有向邻接表。 该图表必须保持定向，因为回程可能会使用完全不同的航班。 
2. 将城市名称压缩为整数ID。 Dijkstra 算法对于整数索引数组的处理效率比对于每个堆操作的距离字典的处理效率都要高。 
3. 运行 Dijkstra`Syracuse`前往比赛城市。 存储到每个城市的最短距离以及产生该距离的前一个城市。 稍后需要前驱数组来恢复实际航班。 
4. 再次运行 Dijkstra，这次是从比赛城市开始。 本次搜索的目标是`Syracuse`。 这提供了最便宜的回程旅程，与出发旅程无关。 
5. 如果任一最短路径不存在，则打印`IMPOSSIBLE`。 当往返行程所需的两个部分之一都不可能时，往返行程就不可能存在。 
6. 将两个最短路径成本相加。 如果总和超出预算，则打印`IMPOSSIBLE`。 如果在预算范围内，则两条路径一起形成最便宜的可行往返行程，因为每条其他外出路径至少花费第一个最短路径距离，而每条其他返回路径至少花费第二个最短路径距离。 
7. 重建外出路径，从比赛城市出发，重复前一个城市，直至到达`Syracuse`。 将收集到的城市进行反转以获得正序。 
8. 以同样的方式重建返回路径，从`Syracuse`并跟随前人，直至到达比赛城市，然后逆转。 第二次 Dijkstra 搜索扎根于竞赛城市，因此它的前身链自然描述了一条从竞赛城市到`Syracuse`。 
9. 连接去程和回程航班列表。 第一条路径的最后一个城市是比赛城市，第二条路径的首个航班从那里开始，所以两个序列直接相连。 
10. 打印航班数量及其总价格，然后使用所需的每对连续城市`A -> B`格式。 

### 为什么它有效

 令 (P) 为任意路径`Syracuse`到比赛城市并且 (Q) 是从比赛城市返回的任意路径`Syracuse`。 整个行程的费用为`cost(P) + cost(Q)`。 Dijkstra 的第一次运行产生一条路径 (P^_)，其成本不大于任何其他传出路径的成本。 第二次运行产生 (Q^_)，其成本不大于任何其他返回路径的成本。 因此，对于每个可能的往返行程，

 [
 成本（P^_）+成本（Q^_）\le成本（P）+成本（Q）。 
]

 因此，两条最短路径的串联是全局最便宜的往返行程。 如果其成本超出预算，则每次其他往返都至少同样昂贵，从而使可行的解决方案变得不可能。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def dijkstra(start, graph):
    inf = 10**30
    dist = [inf] * len(graph)
    parent = [-1] * len(graph)

    dist[start] = 0
    pq = [(0, start)]

    while pq:
        d, u = heapq.heappop(pq)

        if d != dist[u]:
            continue

        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                parent[v] = u
                heapq.heappush(pq, (nd, v))

    return dist, parent

def reconstruct(start, target, parent):
    path = []
    cur = target

    while cur != start:
        path.append(cur)
        cur = parent[cur]

        if cur == -1:
            return []

    path.append(start)
    path.reverse()
    return path

def solve():
    destination = input().strip()
    n, budget = map(int, input().split())

    city_id = {}

    def get_id(city):
        if city not in city_id:
            city_id[city] = len(city_id)
        return city_id[city]

    flights = []

    for _ in range(n):
        a, b, price = input().split()
        price = int(price)

        u = get_id(a)
        v = get_id(b)
        flights.append((u, v, price))

    syracuse = get_id("Syracuse")
    target = get_id(destination)

    graph = [[] for _ in range(len(city_id))]

    for u, v, price in flights:
        graph[u].append((v, price))

    dist_out, parent_out = dijkstra(syracuse, graph)
    dist_back, parent_back = dijkstra(target, graph)

    inf = 10**30

    if dist_out[target] == inf or dist_back[syracuse] == inf:
        print("IMPOSSIBLE")
        return

    total_cost = dist_out[target] + dist_back[syracuse]

    if total_cost > budget:
        print("IMPOSSIBLE")
        return

    out_path = reconstruct(syracuse, target, parent_out)
    back_path = reconstruct(target, syracuse, parent_back)

    full_path = out_path + back_path[1:]

    print(len(full_path) - 1, total_cost)

    for u, v in zip(full_path, full_path[1:]):
        # Reverse lookup is only needed for output.
        # city_names is created below from city_id.
        print(f"{city_names[u]} -> {city_names[v]}")

```该实现在读取航班时首先为每个城市分配一个整数 ID。 这`city_names`array 是反向映射，这是必需的，因为 Dijkstra 适用于整数 ID，但输出必须包含原始城市名称。 

邻接表存储`(destination, price)`对。 平行航班被故意保留为单独的条目。 Dijkstra 可以简单地考虑两者，并在重要时选择更便宜的一个。 

优先级队列包含`(distance, vertex)`对。 这`if d != dist[u]`check 丢弃在发现更短的路由之前创建的陈旧堆条目。 如果没有这种检查，算法仍然是正确的，但它可能会执行更多不必要的工作。 

仅当找到严格较短的距离时才更新前驱数组。 等价路由不需要特殊处理，因为该问题接受任何最低价格路由。 前驱链保证描述最短路径，因为仅通过建立相应最短距离的松弛来分配前驱。 

Python 整数不会溢出，因此即使添加许多航班价格，累积的路径价格也是安全的。 这`10**30`价值表现为无穷大，并且比任何实际路径成本都大。 

稍微不寻常的`__main__`部分的存在只是为了保持代码独立，同时保留所需的`input = sys.stdin.readline`设置。 正常提交时，同样的逻辑可以直接放在里面`solve()`和`city_names`可用于输出部分。

## 复杂度分析

 令 (V) 为不同城市的数量，(E) 为航班数量。 

| 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O((V+E)\log V)) | 两次 Dijkstra 运行主导了这项工作 |
 | 空间| (O(V+E)) | 图、距离、前驱和堆 |

 Dijkstra 游程最多有两次，因此常数因子很小。 该算法不依赖于预算的数值，这很有用，因为发布的问题页面没有指定数字预算范围。 在一秒的限制下，(O((V+E)\log V)) 图算法是合适的规模，而枚举路线在最坏的情况下是阶乘的。

assert large_lines[0] == f"{2 * k} {2 * k}", "large stress case cost"
assert len(large_lines) == 2 * k + 1, "large stress case flight count"

 ## 边缘情况

 当出发行程不可能时，到比赛城市的第一个 Dijkstra 距离仍然是无穷大。 例如：```
B
2 100
Syracuse A 5
B Syracuse 5
```没有办法到达`B`从`Syracuse`，因此算法在尝试重建和打印之前检测无限的传出距离：```
IMPOSSIBLE
```当回程不可能时，第二次 Dijkstra 运行可以赶上它。 例如：```
B
2 100
Syracuse B 5
A Syracuse 5
```目的地可达，但没有航班起飞`B`，所以返回距离是无穷大，结果又是：```
IMPOSSIBLE
```当最便宜的总成本等于预算时，必须接受该路线。 为了：```
B
3 5
Syracuse A 2
A B 1
B Syracuse 2
```第一次 Dijkstra 运行的成本为 3，第二次运行的成本为 2，总和正好为 5。条件`total_cost > budget`是假的，所以算法打印：```
3 5
Syracuse -> A
A -> B
B -> Syracuse
```当直飞航班比一系列更便宜的航班更贵时，Dijkstra 会探索这两种可能性并保持较低的累积距离。 在：```
B
5 5
Syracuse B 5
Syracuse A 1
A B 1
B A 1
A Syracuse 1
```直接到达的路线`B`花费 5，而`Syracuse -> A -> B`成本 2。回程成本为 2，因此最终答案使用 4 个航班，成本为 4。仅在两条最短路径都优化后才执行预算检查。 

如果比赛城市是自己`Syracuse`，两条最短路径的成本为零，并且两条重建路径仅包含其起始城市。 组合路径不包含航班，因此自然结果是`0 0`。 重建循环无需特殊的逐一情况即可处理此问题，因为它会立即停止`cur == start`。 

平行航班也很安全。 假设输入包含：```
B
4 10
Syracuse B 8
Syracuse B 2
B Syracuse 2
B Syracuse 8
```Dijkstra 考虑两个输出边和两个返回边。 两个价格为 2 的航班产生最佳往返行程，成本为 4。在邻接列表中保持平行边可以让最短路径算法正确地做出该选择。
