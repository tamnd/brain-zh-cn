 ## 解决方案
 ## 问题理解

 该问题模型对由音符名称表示的一段音乐进行移调。 每个音符都属于十二音半音阶，用名称书写`A, A#, B, C, C#, D, D#, E, F, F#, G, G#`。 第一个输入值告诉我们每个音符应该移动多少个半音。 正值向上移动，负值向下移动。 第二个输入行包含乐曲中的音符序列。 

在对每个音符独立应用相同的半音移位后，所需的输出是相同的序列。 音符之间的相对距离永远不会改变。 例如，移动`E`向上三个半音给出`G`，因为序列是`E -> F -> F# -> G`。 

无需模拟实际的吉他调音。 吉他的描述只是激发操作的动力。 从计算角度来看，问题是从大小为 12 的固定字母表中进行符号转换。 

问题所示的约束并未对序列中的音符数量给出限制性界限，因此安全目标是输入音符数量的线性时间。 对每个音符处理一次的解决方案实际上是最佳的，因为必须生成每个输出音符。 即使半音值的绝对值很大，也可以在不重复应用移位的情况下处理半音值本身。 

一些边缘情况很容易被错误处理。 负移必须环绕半音阶的开头。 例如，```
-1
A
```产生```
G#
```因为向下移动一个半音`A`达到`G#`。 仅从数组索引中减一并忘记循环换行的实现将访问无效位置或产生错误的音符。 

积极的转变可以跨越规模的终点。 例如，```
1
G#
```产生```
A
```因为尺度是循环的。 使用`(index + shift) % 12`自然地处理这个问题。 

十二个或十二个任意倍数的移位必须使每个音符保持不变。 例如，```
12
C# E G
```产生```
C# E G
```因为十二个半音组成一个完整的八度。 只处理小于 12 班次的解决方案在这里会失败。 

音符本身是符号字符串而不是单个字符。 尤其，`#`属于音符名称，所以`G#`必须被视为一个令牌。 用空格分割行可以正确处理这个问题。 

## 方法

 最直接的暴力解决方案是重复地将每个音符移动一个半音。 对于一个转变`k`半音和`m`注意，这执行`|k| * m`注意最坏情况下的转变。 该方法是正确的，因为每个过渡完全对应于一个半音移动，并且执行所需数量的过渡会产生所需的音高。 然而，如果`|k|`很大，这会多次重复相同的十二状态循环并做不必要的工作。 

关键的观察结果是，在模式在下一个八度重复之前，半音音阶恰好包含十二个不同的位置。 将音符移动 12 个半音会返回相同的音符，因此仅移动模 12 的其余部分很重要。 比如说，而不是应用转变，`1,000,000`一次一个半音，我们可以将其替换为`1,000,000 mod 12`，只有四个半音。 

我们可以为每个音符分配一个从 0 到 11 的整数位置。 然后转置音符就变成了普通的模索引操作。 如果注释有位置`p`所需的班次是`k`，它的新位置是`(p + k) % 12`。 Python 的模运算已经给出了负被除数的非负结果，因此负转置不需要特殊分支。 

蛮力方法之所以有效，是因为它明确地模拟了每个半音运动，但当移位很大时就会失败。 通过观察音符系统每十二个半音重复一次，我们可以折叠所有完整的八度音阶并在恒定的时间内处理每个音符。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(|k|m)| O(米) | 对于大班次来说速度太慢 |
 | 最佳 | O(米) | O(米) | 已接受 |

 这里，`m`是音符数，`k`是所要求的半音移位。 

## 算法演练

 1. 按照自然循环顺序存储十二个半音音符，从`A`。 这为每个可能的音符提供了唯一的索引`0`到`11`。 
2. 构建从每个注释名称到其索引的映射。 这让我们可以转换输入注释，例如`F#`在常数时间内进入整数位置。 
3. 读取半音移位并以 12 为模进行减少。 完整的十二个半音组不会改变任何内容，因此只有其余部分可以影响最终音符。 
4. 从第二个输入行读取所有音符名称。 每个以空格分隔的标记代表一个音符，包括诸如`C#`和`G#`。 
5. 对于每个输入音符，找到其当前索引并添加减少的移位。 应用模十二来环绕半音阶。 生成的索引标识转调的音符。 
6. 打印转换后的笔记，用空格分隔，保留其原始顺序。 

### 为什么它有效

 对于每个音符，它在十二音符周期中的位置完全决定了其以一个八度为模的音高。 十二个半音回到同一位置，因此替换原来的移位`k`经过`k mod 12`不会改变请求的结果。 对于位置处的输入注释`p`，将其向上或向下移动`k`半音将其置于位置`(p + k) mod 12`。 该算法精确计算该位置并将其转换回相应的音符名称。 由于每个音符都是使用相同的移位独立变换的，因此整个输出序列是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

NOTES = [
    "A", "A#", "B", "C", "C#", "D",
    "D#", "E", "F", "F#", "G", "G#"
]

INDEX = {note: i for i, note in enumerate(NOTES)}

def solve():
    shift = int(input())
    notes = input().split()

    shift %= 12

    answer = []
    for note in notes:
        pos = INDEX[note]
        answer.append(NOTES[(pos + shift) % 12])

    print(*answer)

if __name__ == "__main__":
    solve()
```这`NOTES`array 定义整个解决方案使用的循环顺序。 开始于`A`是任意的，只要顺序正确地表示相邻的半音即可。 

字典`INDEX`反转该数组，允许输入字符串在恒定时间内转换为其数字位置。 如果没有这种映射，在实践中搜索每个输入标记的十二个音符仍然会很快，但是字典使预期的恒定时间转换变得明确。 

线路`shift %= 12`在处理任何音符之前删除完整的八度音阶。 这对于较大的正向或负向变化特别有用。 Python 的取模行为还使得表达式如`(-1) % 12`等于`11`，这正是向下移动一个半音所需的索引`A`到`G#`。 

表达式`(pos + shift) % 12`执行循环环绕。 没有单独的穿越案例`G#`到`A`或来自`A`向下至`G#`，因此可能发生相差一误差的边界条件较少。 

输入使用`split()`而不是阅读单个字符，因为诸如`C#`由两个字符组成，但代表一个音符。 输出是用生成的`print(*answer)`，它在连续音符之间恰好插入一个空格。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(米) | 每个输入音符都会被转换和移动一次。 |
 | 空间| O(米) | 输出序列包含每个输入音符的一个转换标记。 |

 该算法对每个音符执行恒定量的工作，并且不依赖于以 12 为模减少半音移位的幅度。 由于输出本身包含`m`请注意，线性时间在常数因子范围内是最佳的。 固定的十二音符查找表和字典仅使用恒定的额外空间，而答案需要 O(m) 空间。 

## 测试用例

 该声明提供了两个示例，因此都包含在下面。 自定义案例涵盖单个音符、八度大小的移位、负环绕、正环绕和重复的相同音符。```python
import sys
import io

NOTES = [
    "A", "A#", "B", "C", "C#", "D",
    "D#", "E", "F", "F#", "G", "G#"
]

INDEX = {note: i for i, note in enumerate(NOTES)}

def solve():
    shift = int(input())
    notes = input().split()
    shift %= 12

    answer = [
        NOTES[(INDEX[note] + shift) % 12]
        for note in notes
    ]

    print(*answer)

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        input = old_input

# Provided samples
sys.stdout = io.StringIO()
assert run("-3\nE A D G B E\n") == "C# F# B E G# C#\n", "sample 1"
assert run("3\nE A D G B E\n") == "G C F A# D G\n", "sample 2"

# Minimum-size input
assert run("0\nA\n") == "A\n", "zero shift on one note"

# Complete octave
assert run("12\nC# E G\n") == "C# E G\n", "one octave"

# Negative wraparound
assert run("-1\nA B C\n") == "G# A# B\n", "negative boundary"

# Positive wraparound and repeated values
assert run("13\nG# G# G#\n") == "A A A\n", "positive boundary and repeated notes"

# Restore normal stdout for interactive use of this test file.
sys.stdout = sys.__stdout__
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 |`0`和`A`|`A`| 最小尺寸输入和零偏移 |
 |`12`和`C# E G`|`C# E G`| 完整的八度音程使音符保持不变|
 |`-1`和`A B C`|`G# A# B`| 周期开始时的负面环绕 |
 |`13`和`G# G# G#`|`A A A`| 正环绕、模数减少和重复值 |

 ## 边缘情况

 跨越音符周期开始的负移位由模算术处理。 为了```
-1
A
```输入的注释`A`有索引`0`。 添加移位后，其原始索引为`-1`，Python 计算`-1 % 12`作为`11`。 指数`11`是`G#`，所以输出是正确的`G#`。 

跨越周期结束的正向转变表现为对称的。 为了```
1
G#
```

`G#`有索引`11`。 加一给出`12`， 和`12 % 12`是`0`，映射回`A`。 因此输出是`A`。 

包含一个或多个完整八度音阶的移调在处理前会被减少。 为了```
24
F# A C
```转变变成`0`因为`24 % 12 = 0`。 每个音符都保持其原始位置，因此输出为`F# A C`。 这避免了每个音符执行二十四个不必要的转换。 

包含的注释`#`必须保持单一令牌。 为了```
2
A# C# G#
```这三个标记被查找为`A#`,`C#`， 和`G#`，而不是被分割成单独的字符。 他们的指数是`1`,`4`， 和`11`，两个相加给出索引`3`,`6`， 和`1`，生产`C D# A#`。 

输入可以在第二行包含任意数量的注释，因此实现会处理由`split()`而不是假设该序列恰好包含标准吉他调音的六弦。 示例中的吉他调音是特定的输入序列，而不是对转换本身的限制。
