 ## 解决方案
 ## 问题理解

 我们有两个整数数组。 它们的长度和顺序不一定必须匹配。 检查员应回答`YES`当两个数组包含完全相同的不同值时，无论每个值出现多少次，也无论值出现的顺序如何。 否则应该回答`NO`。 

例如，`[1, 2, 3]`和`[3, 1, 1, 2, 3]`被认为是相等的，因为从第二个数组中删除重复出现的项`{1, 2, 3}`，这也是第一个数组中的值集。 相比之下，`[1, 2, 3, 4]`和`[1, 2, 7]`之所以不同，是因为它们的独特值集不同。 

输入包括`n`，随后是`n`第一个数组的元素，然后`m`，随后是`m`第二个数组的元素。 原始语句给出了 1 秒的时间限制和 256 MB 的内存，但没有公开有用的数值上限`n`和`m`。 这使得渐近行为特别相关。 仅对输入执行一次传递的解决方案优于重复比较元素或执行不必要的工作。 

第一个边缘情况是大量重复输入。 考虑：```
3
1
2
3
5
1
1
2
2
3
```正确的输出是：```
YES
```一个粗心的逐个元素比较数组的实现会拒绝它们，因为它们的长度不同并且因为第二个数组包含重复的值。 实际情况忽略了多重性，因此这种比较是不合适的。 

第二种边缘情况是不同的排序。 考虑：```
3
1
2
3
3
3
1
2
```正确的输出是：```
YES
```直接比较位置会错误地产生`NO`，即使两个数组包含完全相同的不同整数。 

第三种边缘情况是仅在一个数组中作为重复项出现的值。 考虑：```
2
1
2
3
1
1
1
```正确的输出是：```
NO
```删除重复项后，第一个数组变为`{1, 2}`而第二个变成`{1}`。 仅检查较小数组的每个值是否出现在较大数组中的实现可能会意外地接受这种情况，除非它还检查相反方向。 

## 方法

 一种简单的方法是对两个数组进行排序并删除连续的重复项。 排序将相等的值放在一起，因此在重复数据删除之后，可以直接比较两个结果数组。 这是正确的，因为排序消除了原始顺序的相关性，而去重消除了多重性的相关性。 

这种方法的问题是排序成本`O(n log n + m log m)`。 如果两个数组都包含周围`10^5`元素，这意味着数百万次比较。 更准确地说，粗略的比较计数是`n log2 n + m log2 m`，当两种尺寸均为`10^5`。 这在很多环境下是可行的，但对于这个问题来说是不必要的。 

通过对照另一个数组中的每个元素检查每个元素，暴力破解也可能变得更糟。 这就需要`O(nm)`比较。 和`n = m = 10^5`，这达到了`10^10`比较，这远远超出了一秒竞赛解决方案所能承受的范围。 

关键的观察是该问题不关心顺序或频率。 这些正是集合丢弃的两个属性。 将每个数组转换为集合会立即删除重复项，并且集合相等会自动忽略排序。 暴力破解之所以有效，是因为排序和重复数据删除显式地构建了每个数组的规范表示。 观察到只有不同的值才重要，这让我们可以直接使用哈希集构建该表示。 

因此，最佳解决方案就是读取两个数组，构建它们的集合，然后比较这两个集合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 排序、删除重复、比较 |`O(n log n + m log m)`|`O(n + m)`| 已接受，但不必要的工作 |
 | 成对比较|`O(nm)`|`O(1)`除了输入存储之外| 对于大型数组来说太慢 |
 | 设置平等 |`O(n + m)`平均 |`O(n + m)`| 已接受 |

 ## 算法演练

 1. 阅读`n`并消耗下一个`n`整数作为第一个数组。 将每个值插入一个集合中。 该集合正是重要的信息，因为重复出现对所需的答案没有影响。 
2. 阅读`m`并消耗下一个`m`整数作为第二个数组。 出于同样的原因，将每个值插入另一个集合中。 
3. 比较两组。 如果它们包含完全相同的值，则打印`YES`; 否则打印`NO`。 Python 的集合相等性会隐式检查两个方向，因此任一数组中缺少值都会导致比较失败。 
4. 不要比较原始长度。 当一个数组包含重复项时，不同的长度是完全有效的。 例如，长度`3`和`5`在第一个样本中仍然产生相同的集合。 

其工作原理：处理完所有元素后，第一个集合精确包含第一个数组中出现的每个不同值，第二个集合精确包含第二个数组中出现的每个不同值。 当一个数组的每个不同值出现在另一个数组中时，集合相等性完全成立，反之亦然。 这正是通过删除重复项并忽略顺序所描述的条件，因此该算法无法将有效对分类为`NO`或无效的对`YES`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, sys.stdin.buffer.read().split()))
    pos = 0

    n = data[pos]
    pos += 1

    first = set(data[pos:pos + n])
    pos += n

    m = data[pos]
    pos += 1

    second = set(data[pos:pos + m])

    print("YES" if first == second else "NO")

if __name__ == "__main__":
    solve()
```该解决方案将整个输入读取为整数，并通过它推进索引。 这在这里很方便，因为输入格式给出了精确的数组长度，而`sys.stdin.buffer.read()`避免重复的行读取开销。 

第一个切片恰好包含`n`值，因此位置前进`n`阅读之前`m`。 同样的想法也适用于第二个数组。 保持这些边界明确可以防止出现相差一错误，即第二个数组的长度可能会意外地被解释为其元素之一。 

转换为`set`是中心操作。 Python 自动丢弃重复值，因此不需要显式排序或重复删除过程。 Python 整数具有任意精度，因此数组值也不存在整数溢出问题。 

尽管该声明表示数组元素是在单独的行上提供的，但读取空格分隔的整数是等效的，并且使实现对不同的空格布局具有鲁棒性。 

## 工作示例

 对于第一个样本，第一个数组是`[1, 2, 3]`，而第二个数组是`[1, 1, 2, 2, 3]`。 当第二个数组转换为集合时，重复出现的情况就会消失。 

| 步骤|`first`|`second`| 结果 |
 | ---| ---| ---| ---|
 | 读取第一个数组 |`{1, 2, 3}`| 尚未阅读 | |
 | 读取第二个数组 |`{1, 2, 3}`|`{1, 2, 3}`| |
 | 比较 |`{1, 2, 3}`|`{1, 2, 3}`|`YES`|

 该迹线说明了为什么必须忽略多重性。 第二个数组有五个元素，但其集合仅包含三个不同的值，与第一个数组完全匹配。 这是官方的第一个样本。 

对于第二个样本，数组是`[1, 2, 3, 4]`和`[1, 2, 7]`。 

| 步骤|`first`|`second`| 结果 |
 | ---| ---| ---| ---|
 | 读取第一个数组 |`{1, 2, 3, 4}`| 尚未阅读 | |
 | 读取第二个数组 |`{1, 2, 3, 4}`|`{1, 2, 7}`| |
 | 比较 |`{1, 2, 3, 4}`|`{1, 2, 7}`|`NO`|

 价值`3`第二组中缺失，而`7`第一个缺席。 结果设置相等失败。 这是官方的第二个样本。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(n + m)`平均 | 每个数组元素被插入到哈希集中一次，然后进行平均线性时间集比较 |
 | 空间|`O(n + m)`| 这两个集合最多存储每个不同值的一个副本 |

 该解决方案仅执行输入元素数量的线性预期工作。 即使数组包含许多重复值，每个输入元素也会处理一次，并且重复项不会占用额外的集合条目。 由于一秒的限制，这是适合大输入的渐近方法。
