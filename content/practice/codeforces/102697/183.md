 ## 解决方案
 ## 问题理解

 问题要求我们打印第一个`n`在每个倍数之后存活的正整数`3`被删除。 数量`0`也被删除，但由于输出仅包含正整数，因此它永远不会出现在答案中。 幸存的序列开始`1, 2, 4, 5, 7, 8, 10, 11, ...`因此，每个由三个连续整数组成的块恰好贡献了两个幸存者。 

输入包含一个正整数`n`，必须打印的存活整数的数量。 输出包含那些`n`整数，每行一个。 官方声明给出了1秒的时间限制和256MB的内存，没有明确的上限`n`显示在问题页面上。 由于输出本身包含`n`整数，任何解决方案都必须至少花费`O(n)`时间只是写答案。 不需要做更多线性工作的算法。 

第一个微妙的情况是`n = 1`。 答案是`1`， 不是`0`， 因为`0`被明确销毁。```
1
```正确的输出是：```
1
```一个从以下位置开始搜索的实现`0`并对待每个非倍数`3`因为幸存者可能会意外打印`0`如果它忘记输出涉及正整数。 

另一种边界情况恰好发生在完整块的末尾。 例如：```
3
```正确的输出是：```
1
2
4
```第三位幸存者是`4`， 不是`3`。 一个粗心的公式，例如`2 * n`或者错误的数字分组很容易包含多个`3`。 

一个更大的例子也说明了为什么连续答案之间的差距不是恒定的：```
5
```正确的输出是：```
1
2
4
5
7
```间隙交替出现`1`和`2`。 因此，尝试使用恒定增量生成答案会失败。 

## 方法

 最直接的解决办法就是模拟破坏过程。 开始于`1`，测试每个整数，并在它不能被整除时打印它`3`。 打印后停止`n`幸存者。 这是正确的，因为测试`x % 3 != 0`正是保持活动状态的整数的定义。 

这里的模拟实际上并没有变得渐近太慢。 在每三个连续的正整数中，恰好有两个幸存下来，因此找到第一个`n`幸存者需要精确检查`n + floor((n - 1) / 2)`正整数。 这最多就是关于`1.5n`模运算，然后是`n`输出操作。 因此暴力法已经是`O(n)`并接受所需输出支持的任何实际输入大小。 

有用的观察是幸存的数量有固定的模式。 每组`3k + 1, 3k + 2, 3k + 3`恰好包含两个幸存值，即`3k + 1`和`3k + 2`。 我们可以使用这个结构来计算`i`直接第一个幸存者，而不是一一检查候选者。 

对于基于一的索引`i`，被破坏的数量的倍数`3`之前`i`-th 幸存者正是`floor((i - 1) / 2)`。 将那些被摧毁的数字添加到幸存者的基于一的位置给出`answer(i) = i + floor((i - 1) / 2)`。 

例如，当`i = 5`，我们得到`5 + 2 = 7`。 什么时候`i = 6`，我们得到`6 + 2 = 8`。 该公式直接产生序列。 

两种方法都是线性的，因为输出本身具有`n`线。 基于公式的解决方案更可取，因为每个打印值都是在恒定时间内计算的，并且序列的结构是明确的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) 除了输出缓冲 | 已接受 |
 | 最佳| O(n) | O(1) 除了输出缓冲 | 已接受 |

 ## 算法演练

 1. 阅读`n`，所需的幸存者数量。 
2. 对于每个基于一的位置`i`从`1`通过`n`, 计算`i + (i - 1) // 2`。 添加的项计算有多少个倍数`3`已经出现在该幸存者之前，因此它将幸存者转移到所有正整数中的实际位置。 
3. 将每个计算值附加到输出并将所有值一起打印。 因为一定有确切的`n`输出线，产生每个答案一次给出所需的线性运行时间。 

### 为什么它有效

 考虑将正整数分成三个块：`1, 2, 3`,`4, 5, 6`,`7, 8, 9`， 等等。 

每个块贡献其前两个数字并销毁其第三个数字。 在幸存者面前，处于一基位置`i`， 确切地`(i - 1) // 2`被破坏的数字已被跳过。 因此它在所有正整数中的值就是它的幸存者位置`i`加上那么多跳过的值。 公式`i + (i - 1) // 2`因此，每个幸存者都按升序排列，没有倍数`3`包括并且没有遗漏剩余的正整数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    ans = []
    for i in range(1, n + 1):
        ans.append(str(i + (i - 1) // 2))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```该循环使用基于一的索引，因为数学公式自然地用第一个幸存者、第二个幸存者等来表达。 为了`i = 1`，公式给出`1`，它处理最小的有效输入，没有特殊情况。 

表达式`(i - 1) // 2`是关键的实施细节。 使用`i // 2`会错误地移动每个奇数索引的幸存者。 例如，在`i = 3`，正确答案是`4`， 尽管`3 + 3 // 2`会产生`4`巧合，但在`i = 5`，正确的表达式给出`7`，而使用不同的舍入约定可能会引入错误。 整数除法之前的减法直接代表位置之前的完整幸存者对的数量`i`。 

Python 整数具有任意精度，因此不存在整数溢出问题。 答案本身只是关于`1.5n`，并且存储输出字符串与输出大小成线性关系。

def solve():
    n = int(input())
    ans = [str(i + (i - 1) // 2) for i in range(1, n + 1)]

def run(inp: str) -> str:

    old_stdin = sys.stdin
    old_input = input

    input = sys.stdin.readline

    old_stdout = sys.stdout
    sys.stdout = io.StringIO()

 ## 边缘情况

 对于`n = 1`，输入是```
1
```循环运行一次`i = 1`。 跳过计数项是`(1 - 1) // 2 = 0`，所以答案是`1 + 0 = 1`。 因此输出正好是`1`，以及被破坏的值`0`永远不会进入正整数序列。 

为了`n = 3`，输入是```
3
```三个迭代产生`1`,`2`， 和`4`。 第三个值大于`3`因为`3`被摧毁了。 该公式说明了这一点`(3 - 1) // 2 = 1`, 给予`3 + 1 = 4`。 

为了`n = 5`，输入是```
5
```生成的值是`1, 2, 4, 5, 7`。 过渡从`5`到`7`再次执行相同的规则：`6`是的倍数`3`，因此必须在第五个幸存者之前跳过一个被破坏的值。 

对于大输入，例如```
100000
```最终答案是`100000 + 99999 // 2 = 149999`。 

正好有`49,999`的倍数`3`从`1`通过`149999`，所以从`149999`正整数叶子`100000`幸存者。 因此，该公式无需任何特殊处理即可处理大边界。
