 ## 解决方案
 ## 问题理解

 该任务是直接应用与温度相关的声速。 对于每个测试用例，我们都会得到以摄氏度为单位的气温以及从扬声器到人群最远边缘的距离（以公里为单位）。 我们需要计算声音传播该距离需要多少秒。 

声音的速度是

 [
 V = 331.3 + 0.606\vartheta
 ]

 其中 (\vartheta) 是以摄氏度为单位的温度，(V) 是以米每秒为单位的测量值。 由于输入的距离单位为公里，因此必须首先将其转换为米。 那么旅行时间就是距离除以速度。 所需答案将打印到小数点后两位。 官方说法给出了1秒的时间限制和256MB的内存。 它没有公开问题页面上测试用例数量的有用数字上限，但该算法每个用例仅使用恒定数量的算术运算，因此运行时间与用例数呈线性关系。 没有理由使用比 (O(n)) 更复杂的算法。 

第一个边缘情况是负温度。 例如，```
1
-1 1.2
```给出的速度为 (331.3 - 0.606 = 330.694) m/s。 距离是1200米，所以答案大约是`3.63`。 假设温度必须为正值的解决方案将拒绝有效输入或计算出错误的速度。 

第二个边缘情况是分数距离。 例如，```
1
7 3.6
```距离是3600米，不是3.6米。 声速为 (335.542) m/s，传播时间约为`10.73`秒。 忘记公里到米的转换会产生小 1000 倍的答案。 

第三种边缘情况是需要舍入的结果。 例如，```
1
24 1.1
```给出的速度为 (345.844) m/s，行程时间约为`3.18068`秒，所以所需的输出是`3.18`。 打印原始浮点值的程序不遵循所需的输出格式。 

如果输入范围允许，第四种边缘情况是零距离。 例如，```
1
20 0
```根本不需要旅行，所以答案是`0.00`。 该公式可以自然地处理这个问题，因为分子为零。 

## 方法

 真正的强力解决方案可以模拟向人群传播的声音，反复推进其位置，直到达到目标距离。 如果距离为（D）公里，速度为（V）米每秒，这样的模拟在前进一秒时大约需要（1000D/V）次迭代，如果使用较小的时间增量来获得所需的精度，则需要更多的迭代。 确切的最坏情况计数取决于最大距离和温度，并且已发布的问题页面未提供这些数字范围。 更重要的是，模拟抛弃了测试用例的速度恒定这一核心事实，因此每次迭代都会重复可以由一个除法代替的工作。 

直接数学方法既简单又快速。 蛮力模拟之所以有效，是因为在每个时间间隔之后我们都知道声音传播了多远。 由于速度在测试用例期间不会改变，因此总行程时间恰好是距离除以速度。 通过观察物理模型已经给出了恒定速度，我们可以将整个模拟简化为一些算术运算。 

对于每个测试用例，根据温度计算速度，将公里转换为米，将距离除以速度，然后打印小数点后两位数的结果。 没有隐藏搜索、图遍历、动态编程状态或迭代近似。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟 | 每个案例的 (O(D/V)) 迭代次数 | (O(1)) | (O(1)) | 太慢而且没必要 |
 | 直接公式| (O(n)) | (O(n)) | (O(n)) 用于存储输出，或 (O(1)) 额外 | 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 接下来的每一行描述一对独立的温度和距离。 
2. 读取温度 (\vartheta) 和距离 (d)（以公里为单位）。 温度可以为负数，因此应将其视为普通有符号数。 
3. 计算声速

 [
 V = 331.3 + 0.606\vartheta。 
]

 这是该问题所需的唯一物理公式。 

1. 将距离从公里乘以 1000 转换为米。这是必要的，因为速度以米每秒为单位测量。 
2. 计算行程时间

 [
 t = \frac{1000d}{V}。 
]

 单位现在可以正确取消：米除以米每秒得出秒。 

1. 打印(t)，精确到小数点后两位。 Python 的浮点格式对普通竞赛输入执行所需的舍入。 

### 为什么它有效

 对于每个测试用例，根据温度计算出的速度在声音传播过程中是恒定的。 在恒定速度下，基本关系是 (d = Vt)，因此重新排列得出 (t=d/V)。 在将输入距离转换为速度公式所使用的相同单位后，该算法准确地使用了这种关系。 由于每个计算值都代表该测试用例的实际行程时间，因此将其格式化为两位小数即可产生所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    ans = []

    for _ in range(n):
        temperature, distance_km = input().split()
        temperature = int(temperature)
        distance_km = float(distance_km)

        speed = 331.3 + 0.606 * temperature
        distance_m = distance_km * 1000.0
        time = distance_m / speed

        ans.append(f"{time:.2f}")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```第一个转换将温度读取为整数，因为该语句指定了整数温度。 距离被读取为浮点值，因为诸如`3.6`和`1.1`是有效的。 

速度计算直接遵循给定的公式。 将常量保留为浮点值可以避免意外的整数运算。 

乘以`1000.0`是从公里到米的单位换算。 它必须在除法之前发生，因为速度以米每秒表示。 

表达式`f"{time:.2f}"`两者都将值四舍五入到小数点后两位，并保证打印尾随零。 例如，`3.1`变成`3.10`，这是输出格式所要求的。 

答案会累积起来并在最后写一次。 这样就避免了重复调用`print`适用于大量测试用例并保持较小的 I/O 开销。 

Python 整数和浮点值对于这里涉及的算术来说已经足够了。 Python中不存在整数溢出问题，计算本身只需要普通的双精度浮点精度。

 ## 边缘情况

 对于负温度，请考虑```
1
-1 1.2
```该算法计算出的速度为 (331.3 + 0.606(-1)=330.694) m/s。 它转换`1.2`公里至`1200`m，然后计算 (1200/330.694)，大约为`3.63`。 计算中没有任何内容假设非负温度，因此直接处理该情况。 

对于分数距离，考虑```
1
7 3.6
```速度为（335.542）米/秒。 距离变为（3600）米，（3600/335.542）大约为`10.73`。 乘以 1000 是关键运算。 如果解可分`3.6`直接通过速度，它将公里数与米每秒混合在一起，产生的结果小了 1000 倍。 

对于零距离，考虑```
1
20 0
```速度为（343.42）m/s，转换后的距离为零。 该除法准确地给出了`0.0`，其格式为`0.00`。 不需要特殊情况。 

对于舍入，请考虑```
1
0 1
```速度为（331.3）米/秒，距离为（1000）米。 时间大约是`3.0184`，必须打印为`3.02`。 格式化为`.2f`自动处理这个问题。 

对于重复的测试用例，请考虑```
3
20 1
20 1
20 1
```每个案件都是独立处理的。 每个速度为 (343.42) m/s，每个距离为 (1000) m，每个结果为`2.91`。 没有状态从一个测试用例传递到下一个测试用例，因此相同的输入对每次都会正确地产生相同的输出。
