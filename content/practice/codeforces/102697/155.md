 ## 解决方案
 ## 问题理解

 我们给定一个整数数组，需要从中计算四个标准统计量：算术平均值、中位数、众数和极差。 所需的输出由这四个值组成，它们的顺序完全相同，每行一个。 原始问题陈述给出了数组大小，然后在下一行给出了所有数组值。 

平均值是所有值的总和除以值的数量。 中位数要求按排序顺序考虑值。 当数组长度为奇数时，中位数是单个中间值。 当长度为偶数时，取中间两个值的平均值。 众数是最常出现的值，而极差是最大值和最小值之间的差。 

已发表的声明没有指定 (n) 的数值上限，因此我们不应依赖于很小的输入大小。 时间限制为一秒，内存限制为256 MB。 重复扫描整个数组以查找每个元素的解决方案需要 (O(n^2)) 时间，并且随着 (n) 的增长而变得不合适。 排序为我们提供了 (O(n \log n)) 中的中值和极值，而频率字典则给出了预期 (O(n)) 中的众数。 这可以轻松地将主要工作留在 (O(n \log n)) 。 

在一些小情况下，粗心的实现可能会产生错误的结果。 对于包含一个值的数组，例如`1`其次是`7`，正确的输出是`7.0`,`7.0`,`7`,`0`。 假设有两个不同的中间位置的实现可能会错误地处理中位数。 

偶数大小的数组是另一种常见的边界情况。 为了`4`其次是`1 2 3 4`，正确的输出是`2.5`,`2.5`,`1`,`3`。 中位数不是这里的数组元素之一，因此使用`a[n // 2]`无条件地给予`3`而不是`2.5`。 

对于有意义的模式来说，重复值是必要的。 为了`5`其次是`2 2 8 1 5`，正确的模式是`2`，因为它出现两次，而其他每个值都出现一次。 这也是提供的样品。 

负值也必须正确处理。 为了`3`其次是`-5 -5 -2`，正确的输出是`-4.0`,`-5.0`,`-5`,`3`。 计算范围为`max - min`自然地处理负数，而取各个元素的绝对值是不正确的。 

该语句要求采用单一模式，但没有定义多个相同频率值的平局打破规则。 下面的实现保留了绑定模式中遇到的第一个值。 该样本具有独特的模式，这是频率扫描的自然行为，仅在发现严格更大的频率时才替换当前模式。 

## 方法

 直接的强力解决方案可以通过一次扫描计算平均值和范围，对数组进行排序以获得中值，然后通过检查每个值与其他值来找到众数。 对于每个 (n) 数组元素，我们扫描所有 (n) 个位置并计算相等的值。 在最坏的情况下，模式计算单独执行精确的 (n^2) 次相等检查。 该方法是正确的，因为会检查每个可能的值并计算其完整频率，因此必须找到最大频率。 它的弱点是二次运行时间。 

蛮力之所以有效，是因为每个统计数据都有一个简单的定义，但重复的频率扫描会做不必要的工作。 如果相同的值出现多次，算法会一次又一次地计算该值。 当我们扫描数组时，频率字典通过存储与每个不同值关联的计数来解决这个问题。 然后，每次出现都会对一个计数器产生影响，因此整个模式计算都符合预期 (O(n))。 

中值创建剩余的非线性部分。 一旦数组排序完毕，中位数和范围都变成直接索引操作。 排序还可以立即给出最小值和最大值。 因此，一种排序为我们提供了所需的所有顺序信息，而频率字典则独立处理重复。 

我们可以在排序之前计算总和，因为总和不依赖于顺序。 我们还可以在同一初始扫描期间构建频率字典。 之后，排序是唯一的 (O(n \log n)) 操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 对于大 n 来说太慢 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取 (n) 和 (n) 个整数。 我们保留数组是因为中位数要求其元素按排序顺序排列。 
2. 在读取值的同时计算总和并构建频率字典。 总和直接给出平均值，而字典让我们无需重复扫描数组即可确定众数。 
3. 按非降序对数组进行排序。 排序后，最小值在索引处`0`，最大的位于索引处`n - 1`，并且中间位置是已知的。 
4. 将平均值计算为`sum / n`。 蟒蛇的`/`运算符产生一个浮点结果，这也为诸如包含整数均值的奇数大小的数组等情况提供了所需的形式。 
5. 从中间位置计算中位数`n`很奇怪。 什么时候`n`是偶数，对索引处的两个中心元素进行平均`n // 2 - 1`和`n // 2`。 这种区别是必要的，因为偶数个观测值有两个中心值。 
6. 通过检查频率字典并保留频率最大的值来查找众数。 当频率相同时，保留第一个遇到的值，而不是用相同的频率替换当前答案。 
7. 将范围计算为`a[-1] - a[0]`。 排序已经将最小值和最大值放在了数组的两端，所以不需要额外的扫描。 
8. 按要求的顺序在单独的行上打印平均值、中位数、众数和极差。 

### 为什么它有效

 排序后，数组的顺序与中位数定义所使用的顺序完全相同，因此所选的中间值或中间值对是正确的。 频率字典包含每个不同值的准确出现次数，因此保留为众数的值具有最大频率。 第一个和最后一个排序元素分别是最小值和最大值，使得它们的差值成为范围。 总和只包含每个输入值一次，因此将其除以 (n) 即可得出平均值。 因此，每个统计数据都是根据该统计数据的定义属性计算得出的。 

## Python 解决方案```python
import sys
from collections import Counter

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    total = sum(a)
    freq = Counter(a)

    a.sort()

    mean = total / n

    if n % 2 == 1:
        median = float(a[n // 2])
    else:
        median = (a[n // 2 - 1] + a[n // 2]) / 2.0

    mode = a[0]
    best_count = 0

    for value, count in freq.items():
        if count > best_count:
            best_count = count
            mode = value

    value_range = a[-1] - a[0]

    print(mean)
    print(median)
    print(mode)
    print(value_range)

if __name__ == "__main__":
    solve()
```第一次扫描构建`total`和`freq`。 在排序之前保留这些值可以避免以后需要从排序的数组中恢复频率。 

致电给`a.sort()`是主要的 (O(n \log n)) 操作。 Python 按升序对整数进行排序，因此`a[0]`和`a[-1]`可以直接用于范围。 

奇数大小的中位数使用`a[n // 2]`。 例如，当`n = 5`，这是索引`2`，第三个元素。 对于均匀尺寸，例如`n = 6`，中间位置是索引`2`和`3`，这正是`n // 2 - 1`和`n // 2`。 

明确的`float`奇数中位数的转换使其类型与偶数情况一致。 因此，中位数为整数的输入仍然可以产生输出，例如`2.0`，匹配样本的表示。 

模式扫描使用`>`而不是`>=`。 这意味着绑定频率不会覆盖当前模式。 Python字典保留插入顺序，因此选择的绑定模式是扫描期间第一个频率达到最大值的模式。 

Python整数具有任意精度，因此在计算端点之间的和或差时不存在整数溢出问题。 

## 工作示例

 ### 示例 1

 提供的样品是：```
5
2 2 8 1 5
```初始总和是`18`，频率字典为`{2: 2, 8: 1, 1: 1, 5: 1}`。 分选产品`[1, 2, 2, 5, 8]`。 

| 步骤| 排序数组 | 总和 | 中间值| 模式| 范围 |
 | --- | --- | --- | --- | --- | --- |
 | 读取值 |`[2, 2, 8, 1, 5]`| 18 | 18 未计算| 未计算| 未计算|
 | 排序 |`[1, 2, 2, 5, 8]`| 18 | 18`2`|`2`|`7`|
 | 计算统计 |`[1, 2, 2, 5, 8]`| 18 | 18`2`|`2`|`7`|

 平均值是`18 / 5 = 3.6`。 由于长度为奇数，索引`5 // 2 = 2`给出中位数`2`。 价值`2`频率最高，范围为`8 - 1 = 7`。 结果输出正是提供的示例输出。 

### 示例 2

 对于均匀大小的示例：```
4
1 2 3 4
```每个值的频率都是一，因此第一个值仍然是上述平局行为下的众数。 排序不会改变数组。 

| 步骤| 排序数组 | 总和 | 中间值| 模式| 范围 |
 | --- | --- | --- | --- | --- | --- |
 | 读取值 |`[1, 2, 3, 4]`| 10 | 10 未计算| 未计算| 未计算|
 | 排序 |`[1, 2, 3, 4]`| 10 | 10`2, 3`|`1`|`3`|
 | 计算统计 |`[1, 2, 3, 4]`| 10 | 10`2.5`|`1`|`3`|

 平均值是`10 / 4 = 2.5`。 因为有四个元素，所以中位数是`(2 + 3) / 2 = 2.5`。 每个值都出现一次，因此第一个遇到的值，`1`，保持所选模式。 范围是`4 - 1 = 3`。

 ## 边缘情况

 对于单元素数组，确切的输入是：```
1
7
```排序后的数组是`[7]`。 总和是`7`，所以平均值是`7.0`。 由于长度为奇数，索引`1 // 2 = 0`给出中位数`7.0`。 唯一的值具有频率 1，并且是众数，而范围是`7 - 7 = 0`。 输出是`7.0`,`7.0`,`7`,`0`，因此不会尝试访问不存在的第二个中间元素。 

对于偶数大小的数组，请考虑：```
4
1 2 3 4
```排序后，中间的两个值位于索引处`4 // 2 - 1 = 1`和`4 // 2 = 2`, 给予`2`和`3`。 他们的平均值是`2.5`。 仅使用右侧中间位置会错误地报告`3`，这就是奇偶校验是必要的原因。 

对于重复值，请考虑提供的示例：```
5
2 2 8 1 5
```频率字典记录了两次出现`2`每个其他值都有一个。 模式扫描从第一个遇到的值开始，`2`，其计数为 2，并且没有后来的计数更大。 结果是`2`。 分别排序产生`[1, 2, 2, 5, 8]`，所以中位数仍然是`2`范围是`7`。 

对于负值，请考虑：```
3
-5 -5 -2
```总和是`-12`，给出一个平均值`-4.0`。 排序后的数组是`[-5, -5, -2]`，所以中位数是`-5.0`。 模式是`-5`，范围是`-2 - (-5) = 3`。 两个端点的减法直接处理符号，不需要负数的任何特殊情况。 

对于绑定频率，请考虑：```
4
1 1 2 2
```两个都`1`和`2`出现两次。 问题陈述要求采用奇异模式，但没有指定如何解决这种平局。 该实现使用第一个遇到的最大值，因此它返回`1`。 其余统计数据不受影响：平均值为`1.5`，中位数是`1.5`，范围是`1`。 这种行为是确定性的，并且直接遵循严格的`>`模式扫描中的比较。
