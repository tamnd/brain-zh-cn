 ## 解决方案
 ## 问题理解

 我们得到了两串大写字母。 第一个字符串是视力表上实际出现的文本，第二个字符串是读取的文本。 这些字符串具有相同的长度，因此第一个字符串中的每个位置恰好对应于第二个字符串中的一个位置。 

某些字母对在视觉上相似。 相似性是传递的：如果`D`看起来类似于`P`， 和`P`看起来类似于`G`， 然后`D`,`P`， 和`G`都属于同一相似组。 当某个字符所在位置的两个字母相同时，该字符被归类为正确的。 如果它们不同但属于同一相似组，则该角色被认为是接近的。 否则就完全错误了。 

输入给出正确的字符串、解释的字符串，然后是相似关系的数量，后面是对本身。 输出包含三个计数，按正确、接近和错误的顺序排列。 

这里最有用的约束不是大的数字界限，而是每个字母都是大写英文字母这一事实。 因此，相似图只有 26 个可能的顶点。 即使字符串很长，图形本身也很小。 因此，解决方案应该花费基本上线性的时间来读取关系并扫描两个字符串，而不是重复搜索图表。 

该问题的页面指定了 1 秒时间限制和 256 MB 内存限制，但没有发布字符串长度或相似对数量的明确上限。 由于这些值可能足够大，以至于不需要重复的图形搜索，因此自然目标是`O(|s| + n)`时间。 

第一个边缘情况是相同的字母。 考虑：```
A
A
1
A B
```输出是：```
1 0 0
```显式相似关系不得将其变成紧密匹配。 平等优先，因为读得完全正确的字母才算正确。 

第二个边缘情况是传递相似性。 考虑：```
A
C
2
A B
B C
```输出是：```
0 1 0
```一个粗心的实现，只检查是否`A C`直接出现在输入对中将报告该字符错误。 该问题定义了整个连接组件的相似性，因此路径`A -> B -> C`就足够了。 

第三种边缘情况是相似关系，与被比较的字母无关：```
A
C
1
B C
```输出是：```
0 0 1
```事实是`C`类似于`B`并不使它相似`A`。 必须通过图表确定两个特定字母之间的相似性。 

## 方法

 直接的方法是构建一个图，其顶点是 26 个字母，其边是声明的相似性对。 对于两个字符串中的每个位置，我们比较相应的字母。 如果它们相等，我们就增加正确的计数器。 否则，我们可以从正确的字母开始进行图形搜索，并检查解释的字母是否可达。 可达性完全符合相似度的传递定义，因此该方法是正确的。 

对每个位置进行独立搜索的问题在于，同一个小图会被一次又一次地搜索。 如果字符串有长度`L`并且有`n`输入对，一个 BFS 或 DFS 最多可以检查 26 个顶点，`2n`邻接条目。 对每个角色重复此操作最多可能需要`L(26 + 2n)`顶点和边检查。 输入本身只需要描述图形一次，因此不需要重复这项工作。 

关键的观察是传递相似性正是无向图中的连通性。 由于该图仅包含 26 个字母，因此我们可以计算一次其连通分量。 不相交集并集结构（也称为 DSU 或并集查找）在这里特别自然。 每当输入表明两个字母相似时，我们就会合并它们的组成部分。 处理完所有对后，当两个不同的字母的 DSU 代表相等时，它们恰好是相似的。 

蛮力之所以有效，是因为它通过显式地遵循图中的路径来回答每个相似性问题，但当字符串中有很多位置时会失败。 观察到所有位置都查询相同的 26 个字母图，我们可以对图进行一次预处理。 随后的每个比较都会变成一对几乎恒定时间的 DSU 操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(L(26 + n))`|`O(26 + n)`| 对于大型来说太慢`L`和`n`|
 | 最佳 |`O(n α(26) + L α(26))`|`O(26 + n)`| 已接受 |

 这里`L`是字符串长度，`α`是阿克曼反函数，对于任何实际输入大小来说，它实际上都是常数。 

## 算法演练

 1. 创建一个 DSU，其中包含 26 个大写字母中的每一个的一个单独组件。 最初，没有两个不同的字母是相似的。 
2. 读取每个相似对并合并两个对应的字母。 如果几对通过中间字母连接，重复的并集自然会合并整个连接的组件。 例如，处理`A B`进而`B C`使`A`,`B`， 和`C`共用一名代表。 
3.逐个位置扫描两个字符串。 如果两个字母相等，则立即增加正确的计数器。 此检查必须在相似性检查之前进行，因为相同的字母被分类为正确，而不仅仅是接近。 
4. 对于不同的字母，比较其 DSU 代表。 相等代表意味着字母处于相同的相似性组件中，因此增加接近计数器。 不同的代表意味着它们之间不存在相似关系链，因此增加错误的计数器。 
5. 按要求的顺序打印三个计数器。 

不变的是，在处理完所有相似对之后，当且仅当存在连接它们的声明的相似关系链时，两个字母具有相同的 DSU 代表。 每个联合仅添加一个声明的关系，因此无法合并不相关的组件。 相反，每条关系路径都是逐边处理的，因此该路径上的所有字母最终都会收到相同的代表。 然后根据正确、接近或错误的定义对每个字符串位置进行分类。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)

        if a == b:
            return

        if self.size[a] < self.size[b]:
            a, b = b, a

        self.parent[b] = a
        self.size[a] += self.size[b]

def solve():
    s = input().strip()
    t = input().strip()
    n = int(input())

    dsu = DSU(26)

    for _ in range(n):
        a, b = input().split()
        x = ord(a) - ord('A')
        y = ord(b) - ord('A')
        dsu.union(x, y)

    correct = 0
    close = 0
    wrong = 0

    for a, b in zip(s, t):
        if a == b:
            correct += 1
        else:
            x = ord(a) - ord('A')
            y = ord(b) - ord('A')

            if dsu.find(x) == dsu.find(y):
                close += 1
            else:
                wrong += 1

    print(correct, close, wrong)

if __name__ == "__main__":
    solve()
```这`DSU`类为每个字母存储一个父级。`find`返回组件的代表并执行路径压缩，同时`union`将两个组件组合在一起，并将较小的组件连接到较大的组件下方。 

转换`ord(ch) - ord('A')`地图`A`通过`Z`为整数`0`通过`25`。 这使图形表示保持紧凑，并避免使用字典或基于字符串的图形节点。 

在检查字符串之前处理相似对。 这种顺序很重要，因为像这样的一对`A B`，随后是`B C`，在比较时必须已经合并了所有三个字母`A`相对`C`被制成。 

比较循环显式测试`a == b`第一的。 如果没有该分支，则字母恰好位于同一 DSU 组件中的相同对将被错误地视为接近。 

Python整数具有任意精度，并且所有计数器最多为字符串长度，因此不存在溢出问题。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(n α(26) + L α(26))`| 每个相似对执行一次并集，每个字符串位置最多执行两次查找 |
 | 空间|`O(n + 26)`| DSU 使用 26 个节点，而输入本身需要存储程序读取的字符串和对 |

 由于字母宇宙只有 26 个顶点，`α(26)`实际上是一个常数。 因此，实际运行时间与相似关系的数量和字符串的长度呈线性关系。 这非常适合问题指定的 1 秒和 256 MB 限制。

 ## 边缘情况

 对于相同的字母，输入```
A
A
1
A B
```开始于`A == A`，所以算法递增`correct`并且从不检查 DSU。 结果是`1 0 0`。 这可以防止相等被视为较弱形式的相似性。 

对于传递相似性，请考虑：```
A
C
2
A B
B C
```第一个联合创建组件`{A, B}`。 第二个工会合并`C`进入该组件，给出`{A, B, C}`。 当比较字符串时，`A != C`，但是两个字母有相同的代表，所以结果是`0 1 0`。 

对于不相关的字母，请考虑：```
A
C
1
B C
```唯一包含多个字母的组件是`{B, C}`。`A`仍然处于孤立状态，所以`find(A) != find(C)`。 结果是`0 0 1`。 

最后的边界情况是一个长字符串，其中每个位置都需要传递查找。 拥有100000份`A`在正确的字符串中，100000 个副本`C`在解释的字符串和关系中`A B`和`B C`，每个位置都很接近。 DSU 构建一次，每个位置仅执行恒定时间组件检查，产生`0 100000 0`。 在这种情况下，预处理 26 个字母的图形比为每个字符运行单独的图形搜索更可取。
