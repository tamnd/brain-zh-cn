 ## 解决方案
 ## 问题理解

 这棵树从一个分支开始。 假设当前有 (b) 个分支。 第二天，树创建了 (n \cdot b) 个新分支，因此总数变为

 [
 b+n b=(n+1)b。 
]

 每天使用相同的(n)值，且(n>1)。 从一个分支开始，经过 (k) 天，分支数为

 [
 (n+1)^k。 
]

 任务是找到给定数字 (x) 可能出现的最小有效值 (n)。 官方说法给出（x<10000），时间限制为一秒，内存为256MB。 

关键的变换是定义(a=n+1)。 由于 (n>1)，我们需要 (a\ge3)，并且我们正在寻找最小的 (a\ge3)，使得对于某个正整数 (k) (x=a^k) 。 则所需答案为(a-1)。 

小界限 (x<10000) 意味着即使是简单的搜索也足够快。 尽管如此，该结构给了我们一个更清晰的界限：如果 (x=a^k) 与 (k\ge2)，则 (a^2\le x)，所以 (a\le\sqrt{x})。 我们只需要测试直到 (\sqrt{x}) 的基数，然后单独处理一日情况。 

有两种边界情况值得区分。 如果 (x=1)，则树在发生任何增长之前已经有一个分支，因此允许的最小值为 (n=2)。 例如，输入`1`有输出`2`。 坚持执行至少一个增长步骤的解决方案将错误地拒绝这种情况。 

(x=2) 还存在一个规范问题。 没有 (n>1) 可以产生两个分支，因为第一次增长将一个分支变成 (n+1\ge3) 个分支。 因此输入`2`根据已发布的规则没有有效的输出。 该声明仅表示 (x) 为正，因此它应该隐式排除该值。 官方测试数据必然要避免这样的输入，因为不存在满足规定要求的输出。 

一个常见的实现错误是允许基数 (2)。 用于输入`64`，基数 (2) 会建议 (n=1)，但禁止 (n=1)。 正确答案是`3`，因为 (64=4^3)。 从基数 (3) 开始搜索可以避免此错误。 

另一个错误是只检查方块后就停止。 用于输入`27`，答案是`2`，因为 (27=3^3)。 仅检查 (x) 是否具有整数平方根会漏掉这种情况。 

## 方法

 最直接的暴力方法是尝试从 (2) 向上的所有可能的 (n)。 对于候选 (n)，从 (1) 开始，将分支总数重复乘以 (n+1)，直到达到 (x) 或超过 (x)。 如果达到 (x)，则该候选项就是答案，因为我们按升序测试了 (n)。 

这种方法是正确的，因为固定（n）的增长过程是完全确定的。 顺序是

 [
 1,\ n+1,\ (n+1)^2,\ (n+1)^3,\l点
 ]

 so simulating it tells us exactly whether (x) can occur.

 在实际约束下（x<10000），这个蛮力已经足够快了。 对于最大相关值（x=9999），测试每个候选值最多需要（n）的 9997 个候选值。 如果我们计算模拟候选项时使用的每个乘法，最坏的情况约为 20,124 次乘法。 对于一秒的限制来说这是很小的。 So calling this approach "too slow" for the published constraints would be inaccurate. 它的弱点是它与 (x) 成线性比例，而数学结构让我们做的工作少得多。 

有用的观察是，一个非平凡的幂 (x=a^k)，其中 (k\ge2) 必须具有 (a^2\le x)。 因此它的底数不能超过 (\sqrt{x})。 We can test only (a=3,4,\ldots,\lfloor\sqrt{x}\rfloor). 对于每个基数，重复乘法确定该基数的某个幂是否等于 (x)。 我们按升序测试碱基，因此第一个成功的碱基自动成为最小可能碱基，因此给出最小值 (n)。 

如果 (\sqrt{x}) 以内的底数都不起作用，则 (x) 不是指数至少为 2、底数至少为 3 的幂。 唯一剩下的可能性是恰好一天后达到 (x)，这意味着 (x=n+1)，所以答案是 (x-1)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(x\log x)) | (O(1)) | (O(1)) | 接受 (x<10000)，但范围超出必要 |
 | 最佳 | (O(\sqrt{x}\log x)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 读(x)。 如果 (x=1)，则输出 (2)，因为不需要增长，并且 (2) 是 (n) 的最小允许值。 
2. 将(a=n+1)作为指数增长的基数。 由于 (n>1)，开始从 (3) 测试 (a)。 
3. 测试每个碱基 (a) while (a^2\le x)。 对于每个碱基，从`value = a`当它小于(x)时，反复乘以(a)。 
4. 如果重复乘法恰好达到 (x)，则 (x=a^k) 对于某些 (k\ge2) 而言。 由于碱基是从小到大进行测试的，因此这是最小的有效碱基。 输出（a-1）。 
5. 如果没有碱基成功，则输出(x-1)。 这代表一日增长 (1\rightarrow x)，因为选择 (n=x-1) 会创建 ((x-1)\cdot1) 个新分支并留下 (x) 个分支。 

搜索可以停在 (\sqrt{x}) 的原因是，每个指数至少为 2 的幂都有一个底数，其平方最多为 (x)。 任何更大的基数只能以指数 1 达到 (x)，并且这种情况已由 (n=x-1) 处理。 

### 为什么它有效

 对于固定的(n)，(k)天后的分支数量正好是((n+1)^k)。 因此，找到有效的 (n) 相当于找到 (x=a^k) 的基 (a=n+1\ge3)。 

The algorithm checks every possible base that could have exponent (k\ge2), because such a base must satisfy (a\le\sqrt{x}). 碱基按升序检查，因此第一个精确幂给出了可能的最小值 (a)，因此给出了可能的最小值 (n=a-1)。 如果不存在，则每个有效表示都必须使用指数一，给出 (n=x-1)。 这涵盖了每个有效的生长序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x = int(input())

    if x == 1:
        print(2)
        return

    base = 3

    while base * base <= x:
        value = base

        while value < x:
            value *= base

        if value == x:
            print(base - 1)
            return

        base += 1

    print(x - 1)

if __name__ == "__main__":
    solve()
```第一个特殊情况直接处理初始状态。 当(x=1)时，不需要生长树，并且允许的最小值(n)是(2)。 

主循环处理`base`作为 (n+1)，而不是 (n)。 这种区别是解决方案中的核心代数步骤。 开始于`base = 3`强制执行条件 (n>1)。 

对于每个基地，`value`从基地本身开始。 重复乘以相同的基数会生成 (a^2,a^3,\ldots)。 一旦循环停止`value >= x`，因此它在传递目标后不会执行不必​​要的乘法。 

条件`base * base <= x`避免浮点平方根并保证精确的整数比较。 Python 整数也具有任意精度，尽管给定的界限使得溢出无关紧要。 

如果找到准确的功率，`base - 1`是所需的 (n)。 If the entire loop finishes, there is no nontrivial power representation, so the one-day construction gives`x - 1`。 

## 工作示例

 ### 示例 1

 对于 (x=36)，最小可能的底数为 (3)，但 (3) 的幂为 (3,9,27,81)，因此没有一个等于 (36)。 下一个基地是（4），其权力是（4,16,64），再次失败。 底数 (5) 给出 (5,25,125)。 底数 (6) 给出 (6,36)，所以答案是 (6-1=5)。 

| 基础（一）| 检查值 | 结果 |
 | ---| ---| ---|
 | 3 | 3、9、27、81 | 太大|
 | 4 | 4、16、64 | 太大|
 | 5 | 5, 25, 125 | 太大|
 | 6 | 6, 36 | 准确|

 算法在底数 (6) 处停止，给出输出`5`。 这说明了为什么必须按升序检查碱基：第一个成功的碱基直接给出最小值 (n)。 

### 示例 2

 对于 (x=66)，从 (3) 到 (\sqrt{66}) 的每个碱基都无法准确生成 (66)。 

| 基础（一）| 检查值 | 结果 |
 | ---| ---| ---|
 | 3 | 3、9、27、81 | 太大|
 | 4 | 4、16、64、256 | 太大|
 | 5 | 5、25、125 | 太大|
 | 6 | 6、36、216 | 太大|
 | 7 | 7、49、343 | 太大|
 | 8 | 8、64、512 | 太大|

 没有不平凡的力量等于（66）。 剩下的可能性是一个生长日，因此（n+1=66），给出（n=65）。 

这个例子证实了后备情况。 数字不需要是可达的完美幂，因为通过选择 (n=x-1)，可以在一天内达到每个 (x\ge3)。

## 边缘情况

 对于`1`，遇到特殊情况立即停止执行。 这棵树已经从一根树枝开始，所以不需要生长。 由于 (n) 必须大于 1，因此最小的有效选择是`2`，产生输出`2`。 

为了`3`，该算法找不到任何非平凡幂，因为 (\sqrt3<3)。 它到达后备并打印 (3-1=2)。 事实上，在 (n=2) 的情况下，第一天添加 (2\cdot1=2) 个分支，使树从一个分支增加到三个。 

为了`16`，算法测试基础`3`，其幂为 (3,9,27)，然后基数`4`，其权力包括 (16)。 它打印`4-1=3`。 即使 (16=2^4) 这也是正确的，因为 (n=1) 是被禁止的。 

为了`27`， 根据`3`首先进行测试。 值变成`3`,`9`， 和`27`，所以算法立即打印`2`。 这抓住了仅检查平方根而忘记更高幂的常见错误。 

为了`36`，第一个成功的基地是`6`，因为 (36=6^2)。 答案是`5`。 更大的基数，例如`36`也适用于一个生长日，但不是最小的。 

为了`66`，没有碱基来自`3`通过 (\sqrt{66}) 正好到达`66`。 因此，该算法使用一日表示 (66=(66)^1)，它对应于 (n=65)。 这与第二个样本匹配。 

为了`9999`，循环检查所有可能的非平凡碱基，但没有一个准确地产生`9999`。 后备给出`9998`。 该实现从不使用浮点运算，因此平方根边界不会引入舍入误差。
