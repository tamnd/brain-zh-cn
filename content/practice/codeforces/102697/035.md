 ## 解决方案
 ## 问题理解

 我们有一个包含以下内容的列表`n`整数，任务是确定有多少个不同的值至少出现一次。 值的位置并不重要。 例如，列表`2 2 3 5 6`包含四个不同的值`2`,`3`,`5`， 和`6`，所以答案是`4`。 

官方问题页面给出了 1 秒的时间限制和 256 MB 的内存，但发布的声明没有指定上限`n`或列表中的整数值。 这种缺失的界限意味着我们应该选择一种运行时间与输入值的数量呈线性或接近线性的算法，而不是依赖于二次扫描。 在这种设置下，Python 可以轻松处理数十万个简单操作，而二次算法可以快速进行数十亿次比较。 

主要边缘情况来自重复值和不相邻的值。 考虑`1`其次是`1`:```
1
1
```正确的输出是`1`。 计算每个位置的粗心算法会输出`1`这是巧合，但区别变得明显`4`副本：```
4
7 7 7 7
```正确的输出是`1`，因为只有一个不同的值。 计算出现次数而不是不同的值会错误地产生`4`。 

重复项也可以用其他值分隔：```
5
1 2 1 3 2
```正确的输出是`3`，因为不同的值是`1`,`2`， 和`3`。 仅比较相邻元素的方法会错误地处理第二个元素`1`第二个`2`作为新的价值观。 

最后，每个元素都可以不同：```
4
1 2 3 4
```正确的输出是`4`。 在这种情况下，任何意外删除太多值或仅计算重复次数的实现都可能会失败。 

## 方法

 直接的暴力解决方案是检查每个值并将其与之前的所有值进行比较。 对于每个位置`i`，我们可以扫描位置`0`通过`i - 1`并判断当前值之前是否出现过。 如果没有，我们增加答案。 这是正确的，因为一个值在它出现的第一个位置只贡献一次。 

问题在于比较的次数。 在最坏的情况下，当所有值都不同时，第一个值不需要比较，第二个值需要一个，第三个需要两个，依此类推。 总计为`0 + 1 + 2 + ... + (n - 1) = n(n - 1)/2`比较。 为了`n = 100000`， 那是`4,999,950,000`比较，远远超出了 1 秒解决方案可以合理执行的范围。 

关键的观察是，我们实际上并不关心值出现在哪里或出现了多少次。 我们只需要对“我已经看到这个值了吗？”这个问题给出是或否的答案。 哈希集正是为此操作而设计的。 在扫描列表一次时，我们将每个以前未见过的值插入到集合中。 最后，集合的大小正是不同值的数量。 

暴力破解之所以有效，是因为显式检查较早的位置可以告诉我们某个值之前是否出现过，但当列表很大时，它会失败，因为会重复搜索相同的历史记录。 观察到历史可以用一个集合来总结，这让我们可以用预期的恒定时间成员资格检查来替换每次重复的扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 对于大 n 来说太慢 |
 | 哈希集| O(n) 预期 | O(n) | 已接受 |

 ## 算法演练

 1. 阅读`n`和`n`整数。 我们只需要检查每个值一次，因此没有理由保留有关其原始位置的任何信息。 
2. 创建一个空集，名为`seen`。 该集合准确地代表了迄今为止遇到的值。 
3. 从左到右扫描值。 如果当前值不在`seen`，插入它。 值仅在第一次出现时插入，因此每个不同的值都为集合贡献了一个元素。 
4. 处理完所有值后，打印`len(seen)`。 该集合包含输入中每个不同整数的一个元素，因此其大小就是所需的答案。 

不变量是在处理完第一个之后`i`价值观，`seen`完全包含第一个值中的不同值`i`价值观。 最初两组都是空的。 当已经看到下一个值时，该集合保持正确。 当它是新的时，添加它会使集合完全包含迄今为止看到的不同值。 通过归纳，在最终值之后，该集合包含整个数组中的每个不同值，而没有其他值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    values = list(map(int, input().split()))

    seen = set(values)
    print(len(seen))

if __name__ == "__main__":
    solve()
```第一行读取值的数量，第二行读取数组。 该声明将所有`n`值在下一行，所以一个`input()`对于官方格式来说，调用就足够了。 

表达式`set(values)`直接执行整个不同值操作。 Python 的集合由哈希表支持，因此插入和查找整数需要 O(1) 时间。 决赛`len`操作也是恒定时间。 

无需对数组进行排序。 排序也可以在 O(n log n) 内解决问题，但它会执行不必​​要的工作，因为不同值的顺序无关。 也不需要频率字典，因为不要求每个值出现的次数。 

该代码不假设值是正数或受小常数限制。 由于发布的声明仅将它们描述为整数而没有给出数值范围，因此即使出现负值或零，Python 的集合也是一种安全的表示形式。 

## 工作示例

 对于第一个样本，输入是：```
5
2 2 3 5 6
```扫描的行为如下。 

| 当前值|`seen`加工后| 不同计数 |
 | --- | --- | --- |
 | 2 |`{2}`| 1 |
 | 2 |`{2}`| 1 |
 | 3 |`{2, 3}`| 2 |
 | 5 |`{2, 3, 5}`| 3 |
 | 6 |`{2, 3, 5, 6}`| 4 |

 第二次出现`2`不改变集合。 最终集合有四个元素，因此输出为`4`。 这说明了为什么重复发生的事情只能贡献一次。 

对于第二个样本，输入是：```
4
1 2 3 4
```状态的演变如下。 

| 当前值|`seen`加工后| 不同计数 |
 | --- | --- | --- |
 | 1 |`{1}`| 1 |
 | 2 |`{1, 2}`| 2 |
 | 3 |`{1, 2, 3}`| 3 |
 | 4 |`{1, 2, 3, 4}`| 4 |

 每个值都是新的，因此每一步都会增加集合的大小。 最终的答案是`4`，确认没有重复项的数组为每个位置提供一个不同的值。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) 预期 | 每个`n`值被插入到哈希集中，预计插入时间为 O(1)。 |
 | 空间| O(n) | 在最坏的情况下，每个输入值都是不同的，因此该集合包含`n`元素。 |

 因为官方页面给出了1秒的限制但没有公布最大值`n`，线性预期时间解是合适的选择。 该实现还仅使用与不同值的数量成比例的一组，对于典型的竞争性编程输入大小，该组可以轻松地保持在 256 MB 内存限制内。

 ## 边缘情况

 对于单元素列表，例如```
1
42
```该集合开始为空，接收`42`，并以大小结尾`1`。 该算法不依赖于一对元素进行比较，因此最小的有效输入无需特殊情况即可工作。 

对于仅包含重复项的数组，```
4
7 7 7 7
```第一个`7`已插入，而其余三个值已存在。 最终的组合是`{7}`，所以输出是`1`。 这直接处理了计算位置而不是不同值会产生错误结果的情况。 

对于由其他值分隔的重复项，```
5
1 2 1 3 2
```第一个`1`首先`2`插入，第二个`1`被忽略，`3`被插入，最后的`2`被忽略。 结果集是`{1, 2, 3}`，给出输出`3`。 这就是相邻元素比较不够充分的原因。 

对于每个值都不同的数组，```
4
1 2 3 4
```每个成员资格检查都会失败，因为该值以前没有出现过。 所有四个值都进入集合，答案是`4`。 这种情况也代表了暴力方法的最坏情况，因为每个新值都需要扫描所有先前的位置。 

该实现还无需修改即可处理零和负整数等值。 例如，```
5
-2 0 -2 7 0
```产生`3`，因为集合变成`{-2, 0, 7}`。 不需要人工值范围或直接地址数组，这使得解决方案独立于已发布的问题陈述中未声明的数字边界。
