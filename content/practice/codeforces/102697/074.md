 ## 解决方案
 ## 问题理解

 这个问题比标题所暗示的要简单得多。 输入包含多个测试用例，每个测试用例由一个整数组成。 对于每个整数，无限手套唯一相关的能力就是将该数字除以二。 我们必须在其自己的行上打印每个输入数字的结果值。 官方声明指定了 1 秒的时间限制和 256 MB 的内存。 

对于已发布的语句中输入整数的大小没有有意义的算法限制。 这意味着我们不应该围绕迭代值本身构建方法。 直接算术运算是每个测试用例的恒定时间，并且无论输入是小还是大，都是自然的解决方案。 Python 的整数除法运算符`//`在这里不合适，因为奇数必须产生`.5`，如示例所示，其中`35`变成`17.5`。 普通浮点除法`/`准确给出这些整数输入所需的表示。 

第一个边缘情况是偶数。 例如，输入`1`其次是`10`应该产生`5.0`。 使用整数除法的粗心实现会打印`5`而不是所需的浮点值`5.0`。 

第二个边缘情况是奇数。 例如，输入`1`其次是`35`应该产生`17.5`。 一个实现使用`n // 2`会默默地丢弃小数部分并产生`17`，这是不正确的。 

第三种边缘情况是运算的最小自然整数值，`1`。 输入```
1
1
```产生```
0.5
```这会捕获意外假设每个结果都是整数的实现。 

最后的边缘情况是多个测试用例。 例如，```
3
10
1
35
```必须产生```
5.0
0.5
17.5
```输出必须包含每个输入值的一个结果并保留输入顺序。 

## 方法

 故意的暴力解释会模拟减半，而不是直接执行算术运算。 例如，可以在计算一个值包含多少对单元时重复从一个值中减一，并对不匹配的单元进行特殊处理。 这最终确实确定了答案，但它执行的工作与输入的大小成正比，而不是与测试用例的数量成正比。 如果输入值为`10^9`，这样的模拟可能需要大约`5 * 10^8`迭代只是为了发现答案是`500000000`，这远远超出了一秒竞赛程序应该尝试的范围。 

蛮力方法之所以有效，是因为它显式地重建了商和余数，但它失败了，因为问题已经为我们提供了所需的算术运算。 除以二直接同时计算两个部分。 关键的观察结果很简单，每个测试用例都是独立的，并且不存在将一个数字连接到另一个数字的状态。 我们可以读取一个数字，计算`x / 2`，打印结果，并立即移至下一个数字。 

因为Python的`/`运算符执行真正的除法，偶数，例如`32`变成`16.0`，而奇数例如`35`变成`17.5`。 这与问题所使用的整数输入所需的浮点输出完全匹配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个值 O(x) | O(1) | O(1) | 对于大 x 来说太慢 |
 | 直属部门| 每个值 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`n`，必须处理的值的数量。 第一行不代表要除的数字，因此单独消耗。 
2. 准确重复`n`次并读取下一个整数。 加工精确`n`值使输入案例和输出案例之间的对应关系保持明确。 
3. 将整数除以`2`使用`/`。 该运算符是必要的，因为奇数输入需要保留其小数`.5`成分。 
4. 将结果附加到输出并逐行打印所有结果。 首先构建输出可以避免不必要的重复输出操作，并且还可以明确所需的每行一个结果格式。 

为什么有效：对于每个输入值`x`，算法精确计算问题所需的数学量，`x / 2`。 由于每个测试用例都是独立的，因此单独处理每个值不会影响任何其他结果。 因此，输出包含原始顺序中每个输入值的正确一半。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    out = []

    for _ in range(n):
        x = int(input())
        out.append(str(x / 2))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```第一行读作`n`，然后循环消耗恰好那么多的整数，直接对应于算法的前两个步骤。 每个值在除法之前都会转换为整数，因此 Python 执行数字除法而不是字符串操作。 

表达式`x / 2`是中心操作。 使用`/`而不是`//`是关键的实施选择。 例如，`12 / 2`评估为`6.0`， 尽管`35 / 2`评估为`17.5`。 使用`//`会丢失奇数输入的小数部分。 

结果被转换为字符串并存储在`out`。 最后，`"\n".join(out)`每行只产生一个结果，而不添加不必要的尾部换行符。 Python 中不存在整数溢出问题，并且该算法仅使用除输出缓冲区之外的常量附加状态。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个`n`输入值被读取并除一次。 |
 | 空间| O(n) | 输出字符串在打印之前存储。 |

 该算法对每个测试用例仅执行一次算术运算，因此即使大量测试用例也能在法官规定的一秒限制内高效处理。 内存使用量与正在准备的输出量成线性关系，而不是与数字的大小成线性关系。 已发布的问题允许 256 MB 内存。 

对于普通机器大小的整数来说，算术本身是常数时间。 Python 还可以安全地处理任意大的整数，尽管已发布的声明没有提供输入值的数值上限。

 ## 边缘情况

 对于偶数输入，例如```
1
10
```算法读取`10`, 评估`10 / 2`，并得到`5.0`。 小数点`.0`是由浮点除法自然产生的，因此没有特殊的格式化分支。 

对于奇数输入，例如```
1
35
```该算法评估`35 / 2`并获得`17.5`。 这是暴露最常见错误的情况，使用`35 // 2`，这会错误地产生`17`。 

对于最小的测试用例```
1
1
```计算结果是`1 / 2 = 0.5`。 算法中没有任何内容假设结果至少是`1`或者它是积分的，因此无需特殊代码即可处理边界。 

对于多个独立值，```
3
10
1
35
```循环过程`10`， 然后`1`， 然后`35`, 生产```
5.0
0.5
17.5
```一次迭代的状态永远不会在下一次计算中重复使用。 这种独立性正是为什么完整的解决方案可以保留三行算术思想，而不需要更复杂的数据结构或算法。
