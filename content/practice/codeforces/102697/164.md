 ## 解决方案
 ## 问题理解

 Arseny 无限量供应 100 卢布纸币，起始价为`m`一卢布硬币。 当天`i`，他必须至少支付`c_i`卢布。 收银员付钱多了就找零，当天的不满就是退还的纸币和硬币的个数乘以`w_i`。 目标是选择每天支付多少纸币和硬币，以使总不满意最小化。 收到的找零硬币在以后的日子里仍然可以使用。 

能被 100 整除的部分一点也不有趣。 如果`c_i = 100q + r`， 在哪里`0 <= r < 100`，我们总是可以支付`q`注释并单独处理剩余的`r`卢布。 什么时候`r > 0`，有两种有用的方法来处理余数。 我们可以支付`r`硬币，不会找零，或者我们可以额外支付一张 100 卢布纸币并收到`100-r`硬币作为零钱。 后者的成本`(100-r) * w_i`不满。 

约束条件允许`n`达到`100000`，而每个价格和重量最多`100000`。 二次算法已经可以执行`10^10`最坏情况下的操作，远远超出一秒的极限。 我们需要一个`O(n log n)`或更好的解决方案。 每个相关代币数量低于 100 个这一事实是关键的结构简化。 

第一个边缘情况是 100 的精确倍数。例如，```
1 01007
```有答案`0`, 付款后`1 0`。 粗心的实现可能会将每一天都视为在精确付款和支付一张额外票据之间进行选择，但在这里支付额外票据会产生由一张票据组成的 100 卢布找零，这比精确支付要糟糕得多。 

第二个边缘情况是有足够的硬币。 例如，```
1 501503
```有答案`0`, 付款后`1 50`。 测试`m > r`而不是`m >= r`会错误地让收银员收到零钱。 

第三种边缘情况是当天缺少硬币，但可以追溯更改较早的一天。 考虑```
3 0150 50 1501 1 100
```第一天，我们必须收到50个硬币。 第二天，我们就可以花掉这 50 个硬币了。 第三天，我们又缺货了。 最好第二天换成 100 卢布纸币并收到 50 枚硬币，因为更换只需花费`50`，而第三天收到 50 个硬币的费用`5000`。 只考虑当天的贪心算法会错过这次交换。 

## 方法

 直接蛮力方法是考虑每天的两种可能的操作，且余数不为零。 一个操作用硬币支付剩余部分，另一个操作支付一张额外的纸币并收到找零。 对于每一个完整的选择序列，我们可以模拟硬币余额并计算不满意程度。 这是正确的，因为这两个操作涵盖了处理 100 以下部分的所有有用方法，但最多可以有`2^n`不同的选择。 和`n = 100000`， 那是`2^100000`的可能性，所以枚举是完全不可行的。 

有用的观察是，用硬币支付余款会创造一个可以在以后撤销的机会。 假设有一天`i`有余数`r`。 如果我们现在支付`r`硬币，那么我们稍后可以更改该决定，改为额外支付一张 100 卢布纸币。 相对于原来的决定，我们的币余额正好增加了100，而额外的不满是`(100-r) * w_i`。 

最后的数量可以被视为从当天开始额外购买 100 个硬币的**成本`i`**. 每次我们使用硬币支付余款时，我们都会将未来可能的购买存储在优先级队列中。 

现在假设稍后的一天还有剩余时间`r`但少于`r`硬币可用。 我们有两个有意义的选择。 我们今天可以额外付钱并受苦`(100-r) * w_i`，或者我们可以撤消一项先前的确切付款。 撤销之前的任何付款都会给我们 100 个额外的硬币，这足以支付当前的余额，因为`r < 100`。 

由于只需撤消一笔早期付款，因此最好的早期付款是重置成本最小的一笔。 最小堆为我们提供了该候选者`O(log n)`时间。 如果它的成本小于今天采取改变的成本，我们就会撤销它。 否则，我们今天就接受改变。 

这就是中心贪婪交换。 当出现短缺时，要么立即购买所需的 100 个金币，要么通过替换之前购买的最便宜的金币来购买。 没有理由用更昂贵的付款来代替较早的付款。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(2^n * n)`|`O(n)`| 太慢了 |
 | 贪婪 + 最小堆 |`O(n log n)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 对于每个价格，将其分割为`c_i = 100q_i + r_i`。 最初计划支付`q_i`笔记。 仅有的`r_i`影响币的管理。 
2.如果`r_i = 0`, 准确支付`q_i`笔记。 没有任何有用的理由涉及硬币，因为价格已经是 100 的倍数。 
3.如果至少有`r_i`硬币，支付`q_i`注释和`r_i`硬币。 代币余额减少`r_i`，这一天为未来的替代者创造了一个候选人。 用一张额外的票据代替这一确切付款的成本是`(100-r_i) * w_i`，因此将该成本与日期索引一起插入到最小堆中。 
4. 如果少于`r_i`硬币，目前精确支付是不可能的。 目前的替代方案是付费`q_i + 1`笔记并接收`100-r_i`硬币。 它的不满是`(100-r_i) * w_i`。 
5. 在接受该成本之前，检查堆中最便宜的候选者。 用一张额外的纸币代替之前的确切付款，正好多了 100 个硬币。 自从`r_i < 100`，这 100 个硬币足以支付当前的余额。 
6. 如果最便宜的先前替换成本低于当天的变化，则从堆中删除该候选者，用一张额外的注释将其标记为已付款，将其成本添加到答案中，将 100 添加到当前硬币余额，然后花费`r_i`当日的硬币。 
7. 否则，保持之前的所有决定不变。 今天额外支付一张票据，即可收到`100-r_i`硬币，添加`(100-r_i) * w_i`到答案，并将今天的付款标记为使用额外注释。 
8. 每当一天完全用硬币支付时，将其重置成本插入堆中。 如果该日期稍后被替换，则从堆中删除其候选项。 因此，该堆恰好包含仍可用于替换的较早的确切付款。 

关键的不变量是每个堆条目代表前一天，其付款可以从`r`硬币兑换一张额外的 100 卢布纸币，以存储的不满成本恰好再生产 100 枚硬币。 每当当天缺乏足够的硬币时，更换任何一天的硬币都可以使当前的支付变得可行。 选择最便宜的可用替代品是最佳选择，因为所有替代品都提供相同的 100 个额外硬币，因此只是它们的成本不同。 如果之前最便宜的更换并不比今天接受更改便宜，那么更改当天至少与更改前一天一样好。 

## Python 解决方案```python
Pythonimport sysimport heapq
input = sys.stdin.readline

def solve():    n, m = map(int, input().split())    c = list(map(int, input().split()))    w = list(map(int, input().split()))
    notes = [x // 100 for x in c]    rem = [x % 100 for x in c]
    extra = [False] * n    heap = []    answer = 0
    for i in range(n):        r = rem[i]
        if r == 0:            continue
        current_cost = (100 - r) * w[i]
        if m >= r:            m -= r            heapq.heappush(heap, (current_cost, i))            continue
        if not heap or heap[0][0] >= current_cost:            m += 100 - r            answer += current_cost            extra[i] = True            continue
        old_cost, old_i = heapq.heappop(heap)
        extra[old_i] = True        answer += old_cost
        m += 100        m -= r
        heapq.heappush(heap, (current_cost, i))
    out = [str(answer)]
    for i in range(n):        if extra[i]:            out.append(f"{notes[i] + 1} 0")        else:            out.append(f"{notes[i]} {rem[i]}")
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":    solve()
```数组`notes`和`rem`将不可避免的 100 卢布部分与需要硬币的部分分开。 对于标记为的一天`extra`，代码恰好添加了一个注释`notes[i]`并使用零硬币。 否则它会使用原始的音符数并且准确地`rem[i]`硬币。 

堆存储`(replacement_cost, day_index)`。 蟒蛇的`heapq`是一个最小堆，所以`heap[0]`自动是可以替换的最便宜的先前付款。 

当前一天被替换时，当前的硬币余额会收到`100`相对于原始确切支付历史的额外硬币。 然后代码立即减去当前的余数`r`。 自从`r < 100`，所得余额为非负数。 

比较使用`>=`在决定是否替换较早的一天时。 如果两种成本相等，则保留先前的决定并立即进行更改已经是最佳选择，因此任一选择都是有效的。 

Python 整数具有任意精度，这很有用，因为总的不满意程度可以大致达到`100 * 10^5 * 10^5`，远高于有符号 32 位整数的范围。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(n log n)`| 每个非零余数都会插入到堆中一次，并且最多可以删除一次。 |

 ## 边缘情况

 对于 100 的精确倍数，```
1 01007
```余数为零。 该算法完全跳过堆并记下一个注释。 输出是`0`其次是`1 0`。 这避免了处理零余数的常见错误，就好像支付额外的票据可以以某种方式有所帮助一样。 

只要有足够的硬币，```
1 501503
```初始余额为50，剩余也为50。条件`m >= r`成功，因此算法支付一张纸币和 50 个硬币。 没有产生任何变化，答案为零。 在这种情况下，平等是至关重要的。 

一枚硬币太少了，```
1 491501
```确切的付款是不可能的。 没有之前的堆条目，所以唯一的选择是支付两张纸币并获得 50 个硬币。 不满意的是`50 * 1 = 50`，给出输出成本`50`, 付款后`2 0`。 

更多有趣的兑换案例，```
3 0150 50 1501 1 100
```第 1 天没有硬币，因此它支付两张纸币并收到 50 个硬币，成本为 50。第 2 天正好花掉这 50 个硬币，而其重置成本也是 50。第 3 天又没有硬币，找零将花费`50 * 100 = 5000`。 该堆包含替换成本为 50 的第 2 天，因此算法将替换第 2 天。 相对于之前的状态，这会额外增加 100 个硬币，从而允许第 3 天准确支付剩余的 50 个硬币。 最终成本是 100，而不是 5050，这说明了为什么早期的决策必须保留用于以后的贪婪交换。 

所有这些情况背后的不变量都是相同的：堆中记录的确切付款可以转换为一张额外的 100 卢布纸币，以已知成本额外生产 100 枚硬币。 由于每个余数都严格低于 100，因此一次这样的转换就足以修复任何单一硬币的短缺。 堆总是选择最便宜的转换，这正是保持总不满最小所需的交换。
