 ## 解决方案
 ## 问题理解

 该问题定义了六位数字和六个字母之间的固定替换代码：`0`代表`o`,`1`代表`i`,`3`代表`e`,`4`代表`a`,`5`代表`s`， 和`7`代表`t`。 

每个测试用例都是一系列以空格分隔的数字字符串。 每个数字字符串代表一个单词，并且该字符串中的每个数字都可以使用代码独立翻译。 由于更简单的版本保证原始单词仅包含代码所代表的字母，因此不存在歧义。 我们简单地解码每个数字字符串并保留它们之间的空格。 

例如，`74573`变成`taste`：`7 -> t`,`4 -> a`,`5 -> s`,`7 -> t`， 和`3 -> e`。 

官方的限制是 1 秒的时间限制和 256 MB 的内存，但声明没有给出测试用例的数量或每个序列的长度的数字限制。 安全的解释是算法应该与输入量呈线性关系。 随着数字字符串的增长，任何探索可能的单词而不是直接翻译所提供的数字的方法都会变得更加昂贵。 直接扫描每个输入字符是最佳选择，因为不需要对任何字符进行多次检查。 问题页面确认了六个映射、输入格式以及 1 秒、256 MB 的限制。 

有一些小情况可能会暴露粗心的实现。 一个数字就已经是一个完整的单词了。 用于输入```
1
0
```正确的输出是```
o
```假设每个单词至少包含两个数字的实现在这里会失败。 

一个单词可以包含重复的数字。 用于输入```
1
55 555
```正确的输出是```
ss sss
```仅转换不同数字或意外删除重复字符的粗心实现会产生错误的单词。 

数字`0`也很重要，因为它解码为字母`o`。 用于输入```
1
101
```正确的输出是```
ioi
```将数字视为整数而不是字符串可以默默地删除前导零。 例如，`010`必须解码为`oio`， 不是`io`。 

最后，空格分隔单词，并且必须在输出中保留空格。 用于输入```
1
50 50
```正确的输出是```
so so
```逐字符解码整行而不单独处理空格可能会意外连接两个单词。 

## 方法

 最直接的暴力方法是将每个编码数字视为未知单词，并尝试六个允许字母上的所有可能单词。 有长度的数字`L`会有`6^L`可能的话。 我们可以对每个候选单词进行编码，并检查其编码是否与给定的数字匹配。 这是正确的，因为原始单词必须仅由代码表示的六个字母组成，因此枚举所有此类单词最终会包含答案。 

问题是这种搜索呈指数增长。 一个 20 位数字就已经有`6^20 = 3,656,158,440,062,976`可能的候选词。 在 1 秒的限制下，即使是极小的输入线也是不可能的。 蛮力解决的问题比输入实际要求我们解决的问题要困难得多。 

关键的观察结果是映射是一对一的。 每个可能的输入数字都有一个对应的字母，并且该语句保证原始单词中不会出现其他字母。 因此无需猜测任何事情。 当我们读到一个`5`，对应的字母必须是`s`; 当我们读到`7`，它必须是`t`。 每个角色都有一个明确的答案。 

因此，最佳算法从左到右扫描每个输入行。 使用六条目映射替换数字，而复制空格不变。 同样，我们可以将行拆分为数字字符串，独立解码每个字符串，并将解码后的单词与空格连接起来。 任一实现都需要对每个输入字符进行持续的工作。 

蛮力方法之所以有效，是因为它考虑了每个可能的单词，但会失败，因为可能的单词数量是指数级的。 观察到每个编码字符恰好有一个可能的字母，这完全消除了搜索并将问题简化为直接替换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 对于长度为 L 的单词，O(6^L) | 每个候选人 O(L) | 太慢了 |
 | 最佳 | O(N) | 输出 | O(N) 已接受 |

 这里`N`是输入序列中的字符总数。 暴力破解的指数界限适用于最长的单个编码单词，而最佳方法则线性处理完整的输入。 

## 算法演练

 1.读取测试用例的数量。 接下来的每一行代表一个编码句子，因此必须保留完整的行而不是仅读取一个数字。 
2. 将六个数字到字母的映射存储在字典中，其中`0 -> o`,`1 -> i`,`3 -> e`,`4 -> a`,`5 -> s`， 和`7 -> t`。 字典使每个翻译都是恒定时间的查找。 
3. 对于每个测试用例，读取整行并仅删除其尾随换行符。 保留内部空格是必要的，因为它们分隔单词。 
4. 扫描该行中的每个字符。 如果是空格，则直接追加空格。 否则，在映射中查找相应的字母并附加该字母。 
5. 打印解码后的行。 由于每个输入字符都有一个翻译，因此输出是唯一确定的。 

### 为什么它有效

 不变的是，在处理输入行的任何前缀之后，构造的输出正是该前缀的解码版本。 空格被原封不动地复制，因此单词边界被保留。 对于每个允许的数字，映射准确地给出编码规则指定的字母，因此每个解码的字符都是正确的。 一次扩展这个不变性一个字符意味着在最后一个字符之后，完整的输出行正是所需的解码单词序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    mapping = {
        '0': 'o',
        '1': 'i',
        '3': 'e',
        '4': 'a',
        '5': 's',
        '7': 't',
    }

    t = int(input())

    for _ in range(t):
        line = input().rstrip('\n')
        decoded = []

        for ch in line:
            if ch == ' ':
                decoded.append(' ')
            else:
                decoded.append(mapping[ch])

        print(''.join(decoded))

if __name__ == "__main__":
    solve()
```这`mapping`字典直接表示代码，因此对于任何六位数字都没有算术转换或特殊情况。 

该程序读取整个测试用例`input()`而不是重复读取单个标记。 这保留了单词之间的空格。`rstrip('\n')`删除行结尾，同时保留每个有意义的空间不变。 

然后，循环准确地应用算法中描述的变换。 空格被复制，而数字则通过字典翻译。 输入保证每个非空格字符都属于六个允许的数字，因此不需要后备情况。 

输出被组装在一个列表中并连接一次。 这避免了重复构造更大的字符串`+=`，这可能会导致某些字符串构建模式中不必要的复制。 

Python 根本不涉及整数。 将编码值视为字符串也是必要的，因为前导`0`是编码字的一部分，不能消失。

 这里`N`是编码测试用例中的字符总数。 由于该算法仅对每个字符执行恒定时间字典查找或空间复制，因此它与实际输入大小呈线性缩放。 1 秒时间限制和 256 MB 内存限制与此方法完全兼容，因为编码字上没有搜索、递归或嵌套循环。 

## 测试用例

 官方声明提供了一个包含四个测试用例的样本。 该问题没有指定字符数的最大值，因此下面的压力测试使用大输入，而不是声明不存在的正式最大值。```python
import sys
import io

def solve():
    mapping = {
        '0': 'o',
        '1': 'i',
        '3': 'e',
        '4': 'a',
        '5': 's',
        '7': 't',
    }

    t = int(input())

    for _ in range(t):
        line = input().rstrip('\n')
        print(''.join(
            mapping[ch] if ch != ' ' else ' '
            for ch in line
        ))

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_input = input

    try:
        sys.stdin = io.StringIO(inp)
        input = sys.stdin.readline

        old_stdout = sys.stdout
        sys.stdout = io.StringIO()
        try:
            solve()
            return sys.stdout.getvalue()
        finally:
            sys.stdout = old_stdout
    finally:
        sys.stdin = old_stdin
        input = old_input

# Provided sample
sample = """4
50 50
45 15
1 473 4 74573
17 15 70 517
"""

assert run(sample) == """so so
as is
i ate a taste
it is to sit
""", "provided sample"

# Minimum-size input
assert run("1\n0\n") == "o\n", "single digit"

# All digits and repeated values
assert run("1\n013457\n") == "oieast\n", "all six mappings"

# Leading zero and word boundaries
assert run("1\n010 55 707\n") == "oio ss tot\n", "leading zero and spaces"

# All equal values
assert run("1\n777 0000 11111\n") == "ttt oooo iiiii\n", "repeated digits"

# Large stress-sized input
large_word = "013457" * 10000
expected_large = "oieast" * 10000 + "\n"
assert run("1\n" + large_word + "\n") == expected_large, "large input"
```| 测试输入| 预期产出 | 它验证了什么 |

## 边缘情况

 一位数单词，例如```
1
0
```必须产生```
o
```该算法处理单个`0`，执行一次字典查找，并立即打印`o`。 没有关于字长的假设，因此自然会处理尽可能小的输入。 

前导零必须保留为编码字的一部分。 为了```
1
010
```算法访问`0`,`1`， 和`0`, 生产`o`,`i`， 和`o`，所以输出是```
oio
```由于程序永远不会将编码序列转换为整数，因此前导零不会丢失。 

重复的数字需要重复的输出字符。 为了```
1
555
```三者中的每一个`5`字符独立映射到`s`, 给予```
sss
```该算法没有基于集合或重复数据删除操作，因此重复的输入字符在输出中仍然重复。 

空格代表单词之间的边界。 为了```
1
50 50
```第一个`50`变成`so`，复制空格，第二个`50`变成`so`。 最终输出是```
so so
```这就是为什么该解决方案读取每一完整行，而不是将整个测试用例视为一个无差别的数字。 

最后，考虑一个长序列，例如```
1
013457013457013457
```每个字符都被处理一次，产生```
oieastoieastoieast
```不依赖于可能的单词数量，因此运行时间仅随着实际输入的长度而增长。 即使编码序列很大，这种线性行为也是解决方案保持快速的主要原因。
