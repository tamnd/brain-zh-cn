 ## 解决方案
 ## 问题理解

 我们在第一行输入一个明文句子，在第二行输入一个关键字。 任务是用经典的维吉尼亚密码对句子进行加密。 

关键字的每个字母代表字母表中的一个移位，其中`a`意味着移动`0`,`b`意味着移动`1`，依此类推，直到`z`，这意味着移位`25`。 关键字根据需要重复多次，但明文中的空格不会加密，并且不会消耗关键字中的字符。 加密的句子必须保留其原始空格并保留每个明文字母的大小写。 

例如，使用明文`Here is an example test case`和钥匙`fish`，前四个字母使用移位`f`,`i`,`s`,`h`。 空格后的下一个明文字母继续下一个按键字符，而不是重新启动按键。 

已发布的问题有 1 秒时间限制和 256 MB 内存限制。 该语句没有公开限制性的最大明文长度，因此自然目标是对输入的单个线性传递。 工作量与字符数量成正比的算法就足够了，而构造大型辅助结构或重复搜索字母表是不必要的。 

第一个边缘情况是包含空格的明文。 用于输入```
a a
b
```正确的输出是```
b b
```第一个`a`使用钥匙`b`，第二个`a`也使用密钥`b`因为空格被跳过而不是消耗关键字符。 为每个字符推进键索引的实现会错误地为第二个字符使用不同的键位置`a`。 

第二种边缘情况是比明文短的密钥。 用于输入```
abcde
bc
```键序列是`bcbc b`，所以输出是```
bddff
```如果粗心的实现只使用每个关键字符一次，就会用完关键字符而不是返回到开头。 

第三种边缘情况是混合情况。 用于输入```
Az
b
```输出是```
Ba
```使用相同的字母位置计算移位，但结果必须使用原始字母的大小写写入。 将所有内容都视为小写会产生错误的大写。 

## 方法

 直接实现可以模拟维吉尼亚画面。 对于每个明文字母，将其转换为数字`0`到`25`，将对应的关键字符转换为另一个数字，将两个值取模相加`26`，并将结果转换回字母。 如果这是通过搜索每个明文字符的所有 26 个可能的输出字符来实现的，则工作量为`26n`长度明文的字符比较`n`。 这仍然是线性的，因为字母表的大小固定为 26，并且对于实际问题来说，它并不是真的太慢。 然而，它执行了不必要的工作，并使实现比数学运算所需的更加复杂。 

关键的观察结果是，维吉尼亚画面只是模加法。 如果`p`是明文字母的字母表位置，`k`是密钥字母的位置，加密后的位置是`(p + k) mod 26`。 

无需构建画面或搜索它。 我们可以直接计算出答案。 

仅当处理字母明文字符时，密钥索引才会前进。 当遇到空格时，我们直接复制它，并保持键索引不变。 使用最后一个关键字符后，索引以模数环绕`len(key)`。 

蛮力方法之所以有效，是因为它最终执行相同的字母移位，但未能利用 Vigenère 表中的每次查找都有一个简单的算术公式这一事实。 加密是模加法的观察结果将工作量减少到每个输入字符的恒定计算量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(26n) = O(n) | O(26) | 已接受，但不必要的工作 |
 | 最佳 | O(n) | 输出 | O(n) 已接受 |

 ## 算法演练

 1. 读取明文和密钥，仅删除换行符。 我们不能使用删除内部空间的转换，因为这些空间在输出中必须保持不变。 
2. 将键指针设置为`0`。 该指针代表将加密下一个明文字母的关键字符。 
3. 从左到右处理明文。 对于每个空格，将空格附加到结果中并且不更改键指针。 密码会跳过空格，因此下一个实际字母必须继续使用相同的密钥位置。 
4. 对于每个字母字符，获取其字母位置`ord(character.lower()) - ord('a')`。 获取对应的按键shift`ord(key[key_index].lower()) - ord('a')`。 
5. 添加明文位置和密钥移位模数`26`。 模数使得`z`环绕到`a`。 
6. 将结果位置转换回字符。 如果原始明文字符为大写，则将结果也转换为大写。 将加密字符附加到结果中。 
7. 推进键指针并用模包裹它`len(key)`。 这会无限地重复关键字，而无需显式构造重复的字符串。 
8. 打印完成的结果。 由于结果累积在列表中并连接一次，因此程序避免了重复重建不可变的 Python 字符串。 

### 为什么它有效

 在每个字母位置，该算法精确地使用重复关键字中占据该位置的关键字符，因为每个加密字母的关键指针前进一次，并且永远不会超过空格。 加密字母位置计算如下`(plaintext_position + key_position) % 26`，这正是维吉尼亚加密规则。 由于结果被转换回原始大小写，并且所有非加密字符都被原封不动地复制，因此每个输出字符都是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    plaintext = input().rstrip('\n')
    key = input().rstrip('\n')

    result = []
    key_pos = 0
    key_len = len(key)

    for ch in plaintext:
        if ch == ' ':
            result.append(ch)
            continue

        base = ord('A') if ch.isupper() else ord('a')

        p = ord(ch) - base
        k = ord(key[key_pos].lower()) - ord('a')

        encrypted = (p + k) % 26
        out = chr(base + encrypted)

        result.append(out)
        key_pos = (key_pos + 1) % key_len

    sys.stdout.write(''.join(result) + '\n')

if __name__ == "__main__":
    solve()
```前两行读取明文和密钥，同时保留空格。`rstrip('\n')`删除输入换行符，而不从句子中删除有意义的空格。`key_pos`计算加密字母而不是原始字符位置。 这种区别是问题的主要实现细节。 如果明文包含空格，则不修改而继续循环`key_pos`。 

这`base`变量让相同的算术处理大写和小写字母。 为了`A`，字母位置是`0`，同时对于`a`这也是`0`。 加密位置的计算与大小写无关，并且`base`然后用于恢复原始情况。 

模运算处理环绕。 例如，`z`有地位`25`，并添加一个转变`2`给出`(25 + 2) % 26 = 1`，对应于`b`。 

仅在对字母进行加密后，密钥指针才会前进。 写作`(key_pos + 1) % key_len`使按键自动重复。 不存在相差一的问题，因为当前关键字符是在指针递增之前读取的。 

结果存储在列表中，因为重复串联，例如`result += out`可能会导致不必要的字符串复制。 最后加入一次可以提供干净的线性时间结构。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个明文字符只处理一次，每个字符都进行常数时间算术。 |
 | 空间| O(n) | 结果包含每个输入字符一个输出字符。 |

 该算法对明文执行一次传递，并且除了输出之外仅使用恒定的额外状态。 由于没有依赖于输入大小的嵌套循环，也没有关键字的重复构造，因此它随消息长度线性缩放，并且完全符合规定的 1 秒和 256 MB 限制。

 ## 边缘情况

 对于空格，请考虑准确的输入```
a a
b
```第一个`a`有地位`0`和关键人物`b`有转变`1`, 生产`b`。 空格被复制不变，并且键指针保留在第一个键字符的末尾。 第二个`a`因此也使用`b`并成为`b`。 最终输出是`b b`。 

对于关键重复，请考虑```
abcde
bc
```关键位置是`b, c, b, c, b`。 相应的位移是`1, 2, 1, 2, 1`, 给予`b, d, d, f, f`。 输出是`bddff`。 键指针上的模运算产生第三个`b`在前两个关键角色被消耗后。 

对于混合大小写和字母环绕，请考虑```
Az
b
```

`A`有字母位置`0`，并添加移位`b`，即`1`，产生`B`。 为了`z`，位置是`25`，所以添加`1`给出`26`， 和`26 % 26`是`0`, 生产`a`。 原始案例被保留，所以最终的输出是`Ba`。 

对于比消息长的关键字，请考虑```
abc
xyz
```这三个明文字母仅使用`x`,`y`， 和`z`。 他们的轮班是`23`,`24`， 和`25`，所以加密后的位置是`23`,`25`， 和`25`, 给予`xzz`。 关键字的未使用部分永远不需要处理。 

对于完全由空格组成的明文，例如```
     
abc
```每个字符都被直接复制，并且键指针永远不会移动。 输出保持相同的空格序列。 该算法不会尝试为不应加密的字符索引密钥，这避免了不正确的密钥对齐和不必要的工作。
