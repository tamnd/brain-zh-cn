 ## 解决方案
 ## 问题理解

 任务是普通的矩阵乘法。 输入描述两个矩形矩阵，`m1`和`m2`。 前四个整数按顺序给出两个矩阵的宽度和高度。 的行`m1`首先提供，紧接着是所有行`m2`。 

认为`m1`有高度`H1`和宽度`W1`， 尽管`m2`有高度`H2`和宽度`W2`。 对于要定义的矩阵乘法，`m1`必须等于行数`m2`， 所以`W1 = H2`。 结果有`H1`行和`W2`列。 它的条目位于行`i`和列`j`通过取行获得`i`的`m1`， 柱子`j`的`m2`，乘以相应的值，然后将这些乘积相加。 

例如，与```
m1 = [1 2]
     [3 4]

m2 = [5 6]
     [7 8]
```左上角的结果是`1 * 5 + 2 * 7 = 19`，而右下角的结果是`3 * 6 + 4 * 8 = 50`。 因此完整的结果是```
19 22
43 50
```已发表的声明没有给出矩阵维度或元素值的明确数字上限。 它指定的是一秒的时间限制和 256 MB 的内存。 由于直接矩阵乘法算法对由结果行、共享维度位置和结果列组成的每个三元组执行一次乘法和一次加法，因此其运行时间为`O(H1 * W1 * W2)`。 由于语句中没有更强的维度约束，因此没有合理的次二次或优化矩阵乘法要求可供推断。 预期的解决方案是标准的三循环乘法。 

有几种输入情况可能会暴露粗心实施中的错误。 仅具有一行或一列的矩阵是一种简单的边界情况。 例如，```
1 1 1 1
7
6
```产生```
42
```因为只有一对值需要相乘。 假设至少有两行或两列的实现在这里可能会失败。 

矩形矩阵是索引误差的另一个常见来源。 例如，```
3 1 2 3
1 2 3
4 5
6 7
8 9
```产生```
22 28
```因为单行`[1, 2, 3]`与第二个矩阵的每一列相乘。 如果代码意外地将第一个维度视为行数而不是宽度，则会错误地读取矩阵。 

零值也很重要，因为即使矩阵本身非空，结果也可能包含零。 例如，```
2 1 2 1
0 0
5
7
```产生```
0 0
```从第一个乘积而不是从零初始化每个结果单元的粗心实现可能会导致这种情况错误。 

负值是另一个有用的边界检查。 例如，```
2 1 2 1
1 -2
3
4
```产生```
-5 -7
```因为这两个条目是`1 * 3 + (-2) * 4 = -5`和`1 * 4 + (-2) * 5`仅当第二个矩阵有第二行，而该特定输入没有第二行时。 有效的矩形解释由尺寸决定，因此在构建测试时尺寸和行长度必须始终保持一致。 

## 方法

 直接方法完全遵循矩阵乘法的数学定义。 对于每个结果单元格`(i, j)`，迭代共享维度`k`并添加`m1[i][k] * m2[k][j]`到答案。 这是正确的，因为矩阵乘法的定义正是相应行和列之间的点积。 

如果`m1`有尺寸`H1 × W1`和`m2`有尺寸`W1 × W2`， 有`H1 * W2`结果细胞。 计算一个单元可以检查所有单元`W1`共享位置，因此乘法运算的总数恰好是`H1 * W1 * W2`。 执行相同的添加顺序。 对于大小的方阵`n`，这变成了`n^3`运营。 

这里的暴力描述和最优解实际上是相同的。 问题要求我们利用的矩阵中没有额外的结构，并且该语句没有提供特殊的限制，例如稀疏性、二进制值或重复查询。 关键的观察结果是，一旦读取了两个输入矩阵，每个结果条目都是独立的。 我们可以直接从对应的行和列计算每个条目。 

实现可以显式构造转置`m2`并采用行-行点积，或访问`m2[k][j]`直接在最内层循环内。 后者避免了存储另一个矩阵，并且对于这个基本问题所期望的维度来说已经足够简单了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(H1 * W1 * W2)`|`O(H1 * W1 + W1 * W2 + H1 * W2)`| 已接受 |
 | 最佳 |`O(H1 * W1 * W2)`|`O(H1 * W1 + W1 * W2 + H1 * W2)`| 已接受 |

 这里“强力”和“最优”具有相同的渐近复杂度，因为问题直接要求完整的矩阵乘积。 有用的优化是实现清晰并避免不必要的工作，而不是不同的渐近算法。 

## 算法演练

 1. 阅读`W1`,`H1`,`W2`， 和`H2`。 宽度是每行中值的数量，而高度是行数，所以`m1`有`H1`行和`m2`有`H2`行。 矩阵乘法需要`W1 = H2`。 
2. 阅读`H1`行，每行包含`W1`值，并将它们存储为`m1`。 保持行完整使得访问`m1[i][k]`直接的。 
3. 阅读`H2`行，每行包含`W2`值，并将它们存储为`m2`。 我们需要直接访问`m2[k][j]`计算结果单元格时`(i, j)`。 
4. 创建一个结果矩阵`H1`行和`W2`列，最初用零填充。 每个结果条目都是乘积之和，因此即使某些矩阵值为负数，零也是正确的起始值。 
5. 对于每个结果行`i`，迭代每个结果列`j`。 这两个索引完全标识输出矩阵的一个单元。 
6.对于选择的`(i, j)`, 迭代`k`从`0`通过`W1 - 1`并添加`m1[i][k] * m2[k][j]`到结果。 指数`k`从行中选择匹配的组件`i`第一个矩阵和列的`j`第二个矩阵的。 
7. 毕竟`k`值已被处理，结果单元格恰好包含所选行和列的点积。 对每个重复`(i, j)`并打印完成的矩阵。 

### 为什么它有效

 最内层循环的不变式是处理位置后`0`通过`k - 1`，当前结果单元格包含`m1[i][0] * m2[0][j] + ... + m1[i][k-1] * m2[k-1][j]`。 

最初没有处理任何仓位，因此总和为零。 每次迭代都会添加下一个所需的乘积，从而保留不变量。 毕竟`W1`位置已处理完毕，单元格包含行的完整点积`i`的`m1`和列`j`的`m2`。 由于该算法对每个输出位置独立执行此操作，因此生成的矩阵的每个单元格都有其数学上正确的值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    w1, h1, w2, h2 = map(int, input().split())

    m1 = [list(map(int, input().split())) for _ in range(h1)]
    m2 = [list(map(int, input().split())) for _ in range(h2)]

    result = [[0] * w2 for _ in range(h1)]

    for i in range(h1):
        for j in range(w2):
            total = 0
            for k in range(w1):
                total += m1[i][k] * m2[k][j]
            result[i][j] = total

    sys.stdout.write(
        "\n".join(" ".join(map(str, row)) for row in result)
    )

if __name__ == "__main__":
    solve()
```第一行读作`width, height`对于每个矩阵。 此顺序遵循实际的输入格式，即先给出宽度，再给出高度。 将这些值转换为`w1`,`h1`,`w2`， 和`h2`防止颠倒行和列的常见错误。 

第一个列表理解准确地读取`h1`行为`m1`，每行预计包含`w1`价值观。 第二个做同样的事情`m2`。 因为第二个矩阵有`h2 = w1`行，`m2[k]`对每个都有效`k`由乘法循环使用。 

结果矩阵有`h1`行和`w2`列，因为矩阵乘法保留第一个矩阵的行数和第二个矩阵的列数。 每个单元格在其点积累积之前都从零开始。 

最里面的表达式使用`m1[i][k] * m2[k][j]`。 第一个索引对走过一行`m1`，而第二个访问一列`m2`。 交换这些索引中的任何一个都是一个经典的矩阵乘法错误。 

Python整数具有任意精度，因此不存在乘法或累加的整数溢出问题。 

决赛`join`每个结果行恰好生成一个输出行，值之间有空格。 它还避免了每行末尾不必要的尾随空格。

 ## 边缘情况

 一个`1 × 1`乘法将整个算法简化为一次迭代。 为了```

7
6
