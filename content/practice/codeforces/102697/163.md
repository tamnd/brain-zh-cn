 ## 解决方案
 ## 问题理解

 该问题要求我们在整数间隔内生成通常的 FizzBuzz 序列。 我们有两个整数，`a`和`b`，并且必须处理从以下位置开始的每个整数`a`并在之前停止`b`。 对于每个整数，我们通常打印该整数本身。 3的倍数变成`Fizz`，5的倍数变为`Buzz`，两者的倍数变为`FizzBuzz`。 每个结果都打印在自己的行上。 官方问题使用包含下界和排除上限。 

该区间恰好包含`b - a`整数时`a < b`。 不需要数据结构、预处理或复杂的数学技术，因为输出本身对于区间中的每个整数都包含一行。 如果区间包含`k`值，任何正确的程序都必须产生`k`行，因此每个值花费恒定工作量的算法已经是渐近最优的。 规定的时间限制为 1 秒，内存限制为 256 MB，因此实现应避免不必要的存储并有效地构造输出。 

第一个边缘情况是可被 3 和 5 整除的值。对于输入```
15
16
```正确的输出是```
FizzBuzz
```粗心的实施检查`n % 3 == 0`在检查能否被 5 整除之前可能只打印`Fizz`。 必须首先处理组合的情况，或者等效地，必须在打印之前累积两个字符串。 

第二个边缘情况是排它上边界。 用于输入```
11
18
```处理的值是 11 到 17，因此输出以`17`。 数量`18`不得打印。 一个循环写成`range(a, b + 1)`默默地引入了一个相差一的错误。 正确的Python范围是`range(a, b)`。 这种行为在官方的第二个示例中也可见。 

第三种边缘情况是一个不能被两个数字整除的值。 用于输入```
1
3
```输出是```
1
2
```当整除条件都不适用时，程序必须打印原始整数。 无条件地用字符串替换每个值，或者除非找到倍数否则不打印任何内容，都会产生错误的结果。 

## 方法

 直接的方法是访问每个整数`a`通过`b - 1`并确定应该打印什么。 对于每个值，两次模运算足以确定它是否能被 3 和 5 整除。如果两个条件都成立，我们打印`FizzBuzz`; 否则，我们会打印适用的单个替换，如果两者都不适用，我们会打印数字本身。 这是正确的，因为替换规则仅取决于当前整数，因此每个输出行都可以独立确定。 

在这里，暴力实现和最优实现实际上是相同的。 没有隐藏的搜索空间需要优化。 如果区间包含`k = b - a`整数，输出本身有`k`线。 即使是一个想象的算法在不检查值的情况下以某种方式决定所有替换，仍然需要花费 Ω(k) 时间来编写这些行。 直接模拟使用 O(k) 时间，这与不可避免的下限相匹配。 

关键的观察结果是，这是模拟已经达到最佳状态的情况之一。 可除性测试是恒定时间的，问题要求我们输出每个位置而不是总结结果。 尝试导出 Fizz 或 Buzz 值数量的公式不会有帮助，因为我们仍然必须打印它们的确切序列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(b - a) | O(1)，不包括输出存储 | 已接受 |
 | 最佳 | O(b - a) | 如果输出被缓冲 | O(b - a) 已接受 |

 两行之间的区别是概念上的而不是算法上的。 简单的模拟已经是最优的渐近解。 

## 算法演练

 1. 阅读`a`和`b`。 我们需要处理的区间是`[a, b)`， 所以`a`包含在内并且`b`被排除在外。 
2. 迭代每个整数`x`在`range(a, b)`。 每次迭代恰好对应一个所需的输出行。 
3. 检查是否`x`可被 3 和 5 整除。如果是，则产生`FizzBuzz`。 必须在个别情况之前考虑此条件，因为 15 的倍数满足两个整除性测试。 
4. 否则，检查是否`x`能被 3 整除。 生产`Fizz`当它是的时候。 
5. 否则，检查是否`x`能被 5 整除。 产生`Buzz`当它是的时候。 
6. 如果整除条件均不成立，则生成以下的十进制表示形式`x`。 
7. 按原始顺序打印所有生成的行。 缓冲线路避免重复调用`print`，同时仍然使用仅与所需输出成比例的内存。 

不变量很简单：处理第一个之后`i`间隔值，输出完全包含这些值的正确 FizzBu​​zz 表示`i`值的顺序相同。 对于下一个值，互斥决策序列首先考虑可整除的情况，然后考虑个体情况，因此其表示是正确的。 添加该表示会保留不变性，直到中的每个值`[a, b)`已处理。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a = int(input())
    b = int(input())

    ans = []

    for x in range(a, b):
        if x % 15 == 0:
            ans.append("FizzBuzz")
        elif x % 3 == 0:
            ans.append("Fizz")
        elif x % 5 == 0:
            ans.append("Buzz")
        else:
            ans.append(str(x))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```两个输入行被单独读取，因为该语句指定了两个行分隔的整数。 

循环使用`range(a, b)`，它精确地模拟了所需的包含-排除间隔。 使用`range(a, b + 1)`会错误地处理`b`。 

首先测试能被 15 整除相当于测试能被 3 和 5 整除，因为 15 是它们的最小公倍数。 这也使得优先`FizzBuzz`明确的。 一旦该案失败，`elif`链保证只有其中之一`Fizz`,`Buzz`，或选择原始号码。 

答案累积在一个列表中并一次性写入。 这避免了对每个数字进行单独输出操作的开销。 该列表对于算法思想来说不是必需的，但它是大输出的实用Python实现选择。 

Python 整数不会溢出，因此不需要特殊的整数宽度处理。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(b - a) | 中的每个整数`[a, b)`处理一次，每个整数的工作量恒定，加上产生所需输出的成本。 |
 | 空间| O(b - a) | 该实现将所有输出行存储在`ans`在写它们之前。 |

 时间复杂度是最佳的，因为输出本身对于间隔中的每个整数都包含一行。 通过立即打印每个结果，内存使用量可以减少到 O(1) 辅助空间，尽管缓冲输出通常对 Python 的 I/O 性能更友好。 官方限制为 1 秒和 256 MB。 

## 测试用例```python
import sys
import io

def solve():
    input = sys.stdin.readline

    a = int(input())
    b = int(input())

    ans = []

    for x in range(a, b):
        if x % 15 == 0:
            ans.append("FizzBuzz")
        elif x % 3 == 0:
            ans.append("Fizz")
        elif x % 5 == 0:
            ans.append("Buzz")
        else:
            ans.append(str(x))

    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample 1
assert run("1\n16\n") == (
    "1\n"
    "2\n"
    "Fizz\n"
    "4\n"
    "Buzz\n"
    "Fizz\n"
    "7\n"
    "8\n"
    "Fizz\n"
    "Buzz\n"
    "11\n"
    "Fizz\n"
    "13\n"
    "14\n"
    "FizzBuzz"
), "sample 1"

# Provided sample 2
assert run("11\n18\n") == (
    "11\n"
    "Fizz\n"
    "13\n"
    "14\n"
    "FizzBuzz\n"
    "16\n"
    "17"
), "sample 2"

# Minimum-size interval
assert run("1\n2\n") == "1", "single ordinary value"

# Single value that is divisible by both
assert run("15\n16\n") == "FizzBuzz", "FizzBuzz boundary"

# Boundary around multiples of both 3 and 5
assert run("14\n17\n") == "14\nFizzBuzz\n16", "multiple of 15"

# Upper endpoint must be excluded
assert run("3\n6\n") == "Fizz\n4\nBuzz", "exclusive upper bound"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 |`1 / 2`|`1`| 最小普通间隔且无不必要的额外线路 |
 |`15 / 16`|`FizzBuzz`| 两个整除规则同时适用 |
 |`14 / 17`|`14 / FizzBuzz / 16`| 15 倍数左右立即正确处理 |

 ## 边缘情况

 对于组合可分情况，考虑```
15
16
```循环只处理`x = 15`。 自从`15 % 15 == 0`，第一个条件成功并且程序追加`FizzBuzz`。 输出正是`FizzBuzz`。 首先检查 3 整除情况会错误地产生`Fizz`，这就是条件顺序很重要的原因。 

对于排它上限，考虑```
11
18
```该循环访问 11、12、13、14、15、16 和 17。它从不访问 18，因为 Python 的`range(a, b)`排除`b`。 最终输出是```
11
Fizz
13
14
FizzBuzz
16
17
```循环结束于`b + 1`会错误地附加`Fizz`18.

 对于不匹配任何整除规则的值，请考虑```
1
3
```循环访问 1 和 2。两者都不能被 3 或 5 整除，因此这两个值都会进入最终值`else`分支。 输出是```
1
2
```这证实了该算法不会将 FizzBu​​zz 视为过滤操作。 每个输入整数必须恰好产生一个输出行，要么是替换字符串，要么是原始数字。 

这个问题的核心教训是，并非每个 FizzBu​​zz 任务都需要数学捷径。 在这里，所需的输出包含所请求间隔中的每个值，因此直接模拟已经是最佳的。 最干净的解决方案就是尊重区间边界并以正确的优先级顺序应用整除规则。
