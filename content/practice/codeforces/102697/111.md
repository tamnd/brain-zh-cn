 ## 解决方案
 ## 问题理解

 该问题要求我们执行两个反向文本替换之一。 我们收到一条消息、一个单字符密钥和一个单词密钥。 保证单个字符不会出现在关键字内的任何位置。 

该消息决定了我们应该执行哪个方向的替换。 如果消息包含关键字，我们将消息视为加密文本，并用关键字符替换每次出现的关键字。 否则，我们将消息视为纯文本，并用关键字替换每次出现的关键字符。 所需的输出是转换后的消息。 官方声明证实了这个规则，并给出了两个例子`hello world -> hebruhbruho worbruhd`然后再回来。 

已发布的语句中没有明确的大小限制，因此最安全的解释是使解决方案与消息的长度呈线性关系，除了构造结果字符串的不可避免的成本之外。 由于一秒的限制和 256 MB 的内存，如果输入很大，重复搜索和重建消息将变得不必要的昂贵。 Python 的内置字符串替换操作对于这种简单的替换来说已经足够高效地实现，并且关键字不能包含关键字符，这消除了歧义的一个重要来源。 

第一个边缘情况是包含关键字但不包含关键字符的消息。 例如：```
bruh
l
bruh
```该消息包含`bruh`，所以这是一个解密操作。 正确的输出是：```
l
```仅检查关键字符是否出现的粗心解决方案可能会错误地尝试加密。 

第二种边缘情况是既不包含关键字也不包含关键字符的消息。 例如：```
hello
l
xyz
```自从`xyz`如果没有发生，则该操作是加密的。 唯一的`l`被替换，给出：```
hexyz
```关键词的缺失决定了方向，而不是能否真正进行替代。 

第三种边缘情况是多次相邻出现。 例如：```
ll
l
ab
```该消息不包含`ab`，所以两次出现`l`必须更换。 结果是：```
abab
```仅替换第一个出现的位置会默默地给出错误的答案。 

## 方法

 直接暴力法是逐字符扫描消息，并在需要加密或解密时手动查找关键字。 这是正确的，因为每次替换完全由所选方向和当前子字符串决定。 但是，如果关键字有长度`k`并且消息有长度`n`，逐个字符检查每个可能的起始位置可能需要`O(nk)`比较。 在最坏的情况下，如果一条长消息主要由重复字符和一个类似长的关键字组成，则这可以接近`O(n^2)`运营。 

问题的结构让我们避免自己实现任何模式匹配。 我们只需要用另一个固定字符串替换所有出现的一个固定子字符串。 Python 已经提供了这个操作`str.replace`。 

暴力解决方案之所以有效，是因为每次出现的事件都可以独立处理，但它无法利用替换目标在整个消息中是固定的这一事实。 一旦我们通过检查关键字是否出现来确定方向，整个转换就减少为一次调用`replace`。 

保证关键字中不包含关键字符也是有用的。 在加密期间，用关键字替换字符不能在插入的字内再次出现该关键字符。 在解密过程中，用关键字符替换关键字不能创建该关键字的另一个副本。 因此，可以一次性执行该转换，而不必担心替换会递归地触发更多替换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nk) | O(nk) | O(n) | 对于大字符串来说太慢 |
 | 最佳 | O(n + 输出) | O(n + 输出) | 已接受 |

 ## 算法演练

 1. 阅读整条消息，不要删除内部空格。 该消息是一行文本，因此使用`strip()`是不必要的，并且可能会意外地改变有意义的前导或尾随空格。 
2. 读取关键字符和关键字，仅删除这两行中的换行符。 它们是单独的输入值并且不包含空格。 
3. 检查关键字是否出现在消息中的任何位置。 如果是，则该消息被视为已加密，我们必须对其进行解密。 
4. 在解密情况下，将每次出现的关键字替换为关键字符。 呼唤`replace`没有计数会替换所有出现的情况，这正是问题所需要的。 
5. 如果没有出现关键字，则消息被认为是明文，我们必须对其进行加密。 将每次出现的关键字符替换为关键字。 
6. 完全按照生成的结果打印结果消息。 空格和所有其他字符保持不变。 

正确性来自于声明中的决策规则。 该算法首先在关键字出现时选择解密，否则选择加密。 在解密分支中，每次出现的关键字都被关键字符替换，这正是指定的逆运算。 在加密分支中，每次出现的关键字符都被关键字替换。 由于关键字符并不出现在关键字内部，因此插入的关键字不会意外地引入需要进一步替换的另一个关键字符。 因此，生成的消息正是所需的转换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

message = input().rstrip('\n')
key_letter = input().rstrip('\n')
key_word = input().rstrip('\n')

if key_word in message:
    answer = message.replace(key_word, key_letter)
else:
    answer = message.replace(key_letter, key_word)

print(answer)
```第一个`input`读取完整消息，包括空格。 使用`rstrip('\n')`仅删除行终止符，因此保留实际消息。 

接下来的两次读取获得关键字母和关键词。 由于这些值占据自己的行，因此删除换行符就足够了。 

会员资格测试`key_word in message`实现确定操作是加密还是解密的确切规则。 不需要计算出现次数，因为出现一次就足以选择解密分支。 

致电`replace`故意省略可选的计数参数。 有限的替代品，例如`replace(old, new, 1)`只会修改第一次出现的情况，并且当同一个键出现多次时会失败。 

Python 整数在这里无关紧要，因此不存在溢出问题。 也没有需要管理的索引边界，因为内置的子字符串替换在内部处理它们。 

## 工作示例

 ### 示例 1

 对于第一个示例，消息是`hello world`，关键字母是`l`，关键词是`bruh`。 

| 留言 | 关键字母| 关键词| 关键词存在吗？ | 运营| 结果 |
 | ---| ---| ---| ---| ---| ---|
 |`hello world`|`l`|`bruh`| 没有 |`l -> bruh`|`hebruhbruho worbruhd`|

 这个词`bruh`不存在，因此算法选择加密。 两次出现`l`均独立更换。 第一个`l`在`hello`变成`bruh`，第二个`l`成为另一个`bruh`。 

### 示例 2

 对于第二个示例，消息是`hebruhbruho worbruhd`，使用相同的键。 

| 留言 | 关键字母| 关键词| 关键词存在吗？ | 运营| 结果 |
 | ---| ---| ---| ---| ---| ---|
 |`hebruhbruho worbruhd`|`l`|`bruh`| 是的 |`bruh -> l`|`hello world`|

 这次关键字出现了多次，所以算法选择解密。 每一个`bruh`被转换回`l`，重建原始消息。 

这两个例子一起证明了中心不变量：关键字的存在选择相反的操作，并且每次出现都朝那个方向转换。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + 输出) | 扫描消息以查找关键字并进行处理以构造替换的字符串。 |
 | 空间| O(n + 输出) | Python 存储输入消息和结果字符串。 |

 这里`n`是消息的长度。 已发布的问题有 1 秒时间限制和 256 MB 内存限制。 该解决方案仅执行恒定数量的字符串操作，并避免任何显式的二次子字符串搜索，因此它很容易适合预期的约束。 

## 测试用例```python
import sys
import io

def solve():
    input = sys.stdin.readline

    message = input().rstrip('\n')
    key_letter = input().rstrip('\n')
    key_word = input().rstrip('\n')

    if key_word in message:
        return message.replace(key_word, key_letter)
    return message.replace(key_letter, key_word)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        return solve() + '\n'
    finally:
        sys.stdin = old_stdin

# Provided sample 1
assert run("hello world\nl\nbruh\n") == "hebruhbruho worbruhd\n"

# Provided sample 2
assert run("hebruhbruho worbruhd\nl\nbruh\n") == "hello world\n"

# Minimum-size message
assert run("a\na\nb\n") == "b\n"

# Key word occurs repeatedly and adjacently
assert run("abab\nx\nab\n") == "xx\n"

# Message contains neither key word nor key letter
assert run("hello\nx\nxyz\n") == "hello\n"

# Multiple key-letter occurrences
assert run("aaaa\na\nlong\n") == "longlonglonglong\n"

# Large message
large = "a" * 10000
assert run(large + "\na\nxyz\n") == ("xyz" * 10000) + "\n"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 |`a / a / b`|`b`| 最小尺寸输入和单次替换 |
 |`abab / x / ab`|`xx`| 多个相邻关键字出现 |
 |`hello / x / xyz`|`hello`| 两个密钥都没有出现，因此加密不会改变任何事情 |
 |`aaaa / a / long`|`longlonglonglong`| 每次出现都必须替换 |
 |`a...a / a / xyz`| 重复`xyz`| 大输入和线性处理|

 ## 边缘情况

 第一个边缘情况是当消息本身正是关键字时：```
bruh
l
bruh
```会员测试立即成功。 该算法采用解密分支并评估`bruh.replace(bruh, l)`，生产：```
l
```精确匹配不需要特殊情况。 

第二种边缘情况是当关键字不存在并且关键字母也不存在时：```
hello
x
xyz
```测试`xyz in hello`为 false，因此算法选择加密。 自从`x`不会发生，`hello.replace(x, xyz)`保持消息不变：```
hello
```这是正确的，因为问题仅因缺少关键字而选择加密。 

第三个边缘情况包含相邻的出现：```
abab
x
ab
```关键词`ab`发生两次，从位置零和位置二开始。 解密操作同时替换两个出现的位置，给出：```
xx
```在找到匹配项后前进得太远的逐字符实现可能会意外地跳过第二次出现。`str.replace`避免了索引错误。 

第四种边缘情况有重复的关键字母：```
aaaa
a
long
```关键词`long`不存在，因此选择加密。 四个中的每一个`a`字符被替换，结果是：```
longlonglonglong
```关键字不包含`a`，正如声明所保证的，所以没有新插入`a`字符出现并且变换不需要重复进行。
