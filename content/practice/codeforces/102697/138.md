 ## 解决方案
 ## 问题理解

 该问题要求我们检查一个正整数 (n)。 我们需要将除 (n) 本身之外的 (n) 的每个正因数相加。 如果该和等于 (n)，则 (n) 是一个完全数。 输出必须首先使用所需的确切短语来说明是否发生这种情况，然后打印除数和。 存档的问题是 Gym 102697，问题 138，限制为 1 秒，内存为 256 MB。 

例如，当(n=28)时，真因数为(1,2,4,7,14)，其和为(28)，因此输出为`PERFECT NUMBER`其次是`28`。 对于 (n=48)，真因数之和为 (76)，因此输出为`NOT A PERFECT NUMBER`其次是`76`。 

该语句在其显示的约束中没有给出小的显式上限。 相反，它保证计算中涉及的每个值都适合 Java`int`，因此实现不应假设达到 (n) 的试验循环是可行的。 32 位有符号整数大约可以大到 (2.1\times10^9)，迭代每个整数直到达到这样的值将需要数十亿次整除性检查。 即使请求的总和本身符合规定的整数范围，算法仍然必须避免扫描整个区间。 

直接实现可能会错误地处理几种边界情况。 第一个是（n=1）。 它唯一的除数是 (1)，但该除数被排除，因为它是数字本身，因此真除数和是 (0)。 正确的输出是`NOT A PERFECT NUMBER`其次是`0`。 如果粗心的实现将每个输入的总和初始化为 (1)，则会错误地对 (1) 进行分类。 

第二种情况是素数，例如(n=7)。 它唯一的真因数是 (1)，所以答案是`NOT A PERFECT NUMBER`其次是`1`。 仅查找除数对而忘记除数 (1) 的实现可能会产生错误的零之和。 

第三种情况是完全平方，例如(n=36)。 它的除数对 (6\times6) 两次包含相同的除数，因此 (6) 仅需相加一次。 真因数和为 (1+2+3+4+6+9+12+18=55)。 如果平方根像普通除数对一样处理，则（6）被计算两次，结果变为（61）。 

最后，一个真正的完美数，例如 (n=6)，具有真因数 (1,2,3)，正好给出 (6)。 正确的输出是`PERFECT NUMBER`其次是`6`。 这种情况捕获了意外排除一对除数之一的实现。 

## 方法

 最直接的方法是测试从 (1) 到 (n-1) 的每个整数 (d)，检查 (d) 是否整除 (n)，并在整除时将其相加。 这是正确的，因为每个真除数都只被考虑一次。 问题是支票的数量。 对于接近有符号 Java 允许的最大值的输入`int`，这意味着大约 (2.1\times10^9) 模数运算，这远远超出了一秒竞争性编程解决方案所能承受的范围。 

有用的结构是除数成对出现。 如果 (d) 除以 (n)，则 (n/d) 也是除数。 例如，(48) 的约数对为 (1,48)、(2,24)、(3,16)、(4,12) 和 (6,8)。 当我们只需要真约数时，必须排除等于 (n) 的成员，但仍然可以通过这些对找到其他所有约数。 

这意味着我们只需要测试 (\sqrt n) 以内的候选除数。 每当 (d) 除 (n) 时，我们都会添加 (d) 及其配对除数 (n/d)。 如果 (d) 恰好为 (\sqrt n)，则这两个值相同，并且只需相加一次。 我们还需要避免添加 (n) 本身，这种情况发生在 (d=1) 及其配对除数为 (n) 时。 

暴力方法之所以有效，是因为它显式地检查每个可能的真除数，但它会失败，因为搜索间隔与 (n) 一样大。 通过观察除数以互补对的形式到达，我们可以将 (O(n)) 搜索替换为 (O(\sqrt n)) 搜索。 对于 (2\times10^9) 左右的值，这会将除数候选数从数十亿减少到仅约 46,000 个。

 | ---| ---| ---| ---|
 | 蛮力 | (O(n)) | (O(n)) | (O(1)) | (O(1)) | 太慢了 |
 | 最佳 | (O(\sqrt n)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 读取整数 (n) 并将真除数和初始化为零。 从零开始是必要的，因为当 (n=1) 时 (1) 不是真因数。 
2. 从 (1) 迭代 (d) 到 (\lfloor\sqrt n\rfloor)。 我们永远不需要直接检查更大的候选者，因为任何大于 (\sqrt n) 的除数都会与我们在循环中遇到的较小除数配对。 
3. 每当 (d) 除 (n) 时，计算配对除数 (q=n/d)。 ((d,q)) 对给出了与 (d) 值相关的所有除数。 
4. 如果 (d<n)，则添加 (d)。 除了微不足道的情况 (n=1) 之外，对于 (d\leq\sqrt n)，此条件始终成立，但显式编写该条件可以使真除数要求变得清晰。 
5. 如果 (q\neq d) 且 (q<n)，则添加 (q)。 第一个条件阻止完全平方数两次其平方根，而第二个条件阻止 (n) 本身进入真除数和。 
6. 将所得总和与 (n) 进行比较。 打印`PERFECT NUMBER`当它们相等时，否则打印`NOT A PERFECT NUMBER`，然后是第二行的总和。 

### 为什么它有效

 不变量是，在处理每个候选除数 (d\leq\sqrt n) 后，运行和包含已达到其补除数的每个真除数，并且仅包含每个这样的除数一次。 (n) 的每个除数都属于一对 ((d,n/d))，最多有一个成员 (\sqrt n)，因此循环最终会发现每个除数。 条件 (q\neq d) 处理一对折叠成一个值（即完美平方）的唯一情况。 条件 (q<n) 排除 (n) 本身，仅留下真因数。 因此，最终的总和正是问题所需的数量，因此将其与 (n) 进行比较可以得出正确的分类。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    divisor_sum = 0
    d = 1

    while d * d <= n:
        if n % d == 0:
            q = n // d

            if d < n:
                divisor_sum += d

            if q != d and q < n:
                divisor_sum += q

        d += 1

    if divisor_sum == n:
        print("PERFECT NUMBER")
    else:
        print("NOT A PERFECT NUMBER")

    print(divisor_sum)

if __name__ == "__main__":
    solve()
```循环从 (1) 开始，因为 (1) 是每个正整数的约数。 对于每个成功的整除性测试，`q = n // d`无需再次搜索即可给出补除数.

 条件`d * d <= n`优于计算浮点平方根。 它避免了舍入问题，并使整个计算保持在整数算术中。 Python 整数还消除了任何溢出问题，尽管原始语句保证相关值适合 Java`int`。 

添加除数之前的两次检查是精确执行定义的。 什么时候`n = 48`和`d = 1`，这对是`(1, 48)`。 价值`1`被添加，同时`48`被拒绝，因为它是数字本身。 什么时候`n = 36`和`d = 6`，这对是`(6, 6)`，所以第一个条件添加`6`第二个条件拒绝它，因为`q == d`。 

无需存储除数。 我们只需要它们的和，因此单个累加器就足够了。 

## 工作示例

 对于示例 1，输入为`28`。 循环发现的除数对如下所示。 

| (d) | （n/d） | 附加值| 总和 |
 | ---| ---| ---| ---|

 循环在 (d=5) 之后停止，因为 (6^2>28)。 最终的和是 (28)，所以这个数字是完美的，输出是`PERFECT NUMBER`其次是`28`。 该迹线表明，每个除数对都已找到，而数字本身则被排除。

 循环在 (d=6) 之后停止，因为 (7^2>48)。 真除数和为 (76)，与 (48) 不同，因此输出为`NOT A PERFECT NUMBER`其次是`76`。 该迹线说明了为什么仅检查平方根就足够了：较大的除数 (24,16,12,8) 被恢复为 (2,3,4,6) 的配对。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(\sqrt n)) | 最多测试 (\lfloor\sqrt n\rfloor) 个候选除数。 |
 | 空间| (O(1)) | (O(1)) | 仅存储输入、循环变量、配对除数和运行和。 |

 对于接近 (2^{31}-1) 的值，(\sqrt n) 仅约为 46,341。 这对于一秒的限制来说足够小，而 (O(n)) 扫描可能需要超过 20 亿次迭代。 因此，该算法改变了解决方案的实际行为，而不仅仅是改进其常数因子。

 ## 边缘情况

 对于 (n=1)，确切的输入是`1`。 循环从 (d=1) 开始，它除以 (1)，得到 (q=1)。 第一个条件拒绝 (d)，因为 (d<n) 为假，第二个条件拒绝 (q)，因为 (q=d)。 总和保持为零，因此输出为`NOT A PERFECT NUMBER`其次是`0`。 这避免了将 (1) 视为其自身真因数的常见错误。 

对于诸如 (n=7) 之类的素数，找到的唯一约数对是 (1,7)。 该算法添加 (1)，拒绝 (7)，因为它等于 (n)，并获得总和 (1)。 输出是`NOT A PERFECT NUMBER`其次是`1`。 不需要特殊的素数测试，因为除数对过程自然地处理素数。 

对于完美平方 (n=36)，循环最终达到 (d=6)，其中 (q=36/6=6)。 该算法在第一个条件中添加一次 (6)，并拒绝再次添加，因为`q != d`是假的。 其他对贡献 (1,36)、(2,18)、(3,12) 和 (4,9)，(36) 本身被排除在外。 所得总和为 (55)，因此输出为`NOT A PERFECT NUMBER`其次是`55`。 

对于完全数 (n=6)，这对是 (1,6) 和 (2,3)。 该算法添加 (1)，拒绝 (6)，然后添加 (2) 和 (3)，生成 (6)。 平等测试成功，给出`PERFECT NUMBER`其次是`6`。 这证实了相同的除数对机制适用于真正的完美数，而不需要任何已知完美数的硬编码列表。
