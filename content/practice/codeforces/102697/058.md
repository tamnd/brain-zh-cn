 ## 解决方案
 ## 问题理解

 任务是通过更改每个字母字符的大小写来转换一个字符串。 大写字母必须变成其对应的小写字母，而小写字母必须变成大写字母。 字符本身保持相同的位置，并且该语句保证字符串仅包含英文字母，没有空格或其他符号。 官方问题指定了 1 秒时间限制和 256 MB 内存限制。 

例如，输入`HeLlO`变成`hElLo`。 每个位置都是独立处理的，因此字符之间没有交互，也不需要数组、映射或图形等数据结构。 

除了表明输入是一个字符串之外，该语句没有公开有用的显式字符串长度上限。 无论隐藏长度限制如何，算法都必须至少读取每个字符，因此对于长度为 n 的字符串，Ω(n) 时间是不可避免的。 二次解会重复处理已经见过的字符，并且随着 n 的增长而变得不合适。 线性扫描是自然的目标，因为它只对每个字符执行恒定量的工作。 

主要的边缘情况很简单，但很容易处理不当。 单字符字符串，例如`A`应该产生`a`，因为唯一的字符仍然需要切换。 仅包含小写字母的字符串，例如`abc`，应该产生`ABC`; 仅转换大写字符的实现会错误地使输入保持不变。 相似地，`ABC`必须成为`abc`。 最后，一个混合字符串，例如`aBcD`必须成为`AbCd`，因此实现必须独立决定每个位置，而不是对整个字符串应用一次转换。 

## 方法

 直接的暴力解释是处理每个字符并搜索包含所有可能的大写和小写字母的集合，直到找到当前字符。 一旦找到对应项，我们就会将该对应项附加到答案中。 这是正确的，因为每个输入字符都属于 52 个英文字母字符之一。 

如果搜索在最坏情况下为每个输入字符检查 52 个可能的字母，则长度为 n 的字符串可能需要最多 52n 个字符比较。 由于 52 是一个常数，因此从技术上讲，这是 O(n)，因此与许多强力方法不同，它不会变得渐近太慢。 它的弱点是，当可以直接从字符值确定大小写时，它会执行不必​​要的比较。 

关键的观察结果是，大写和小写英文字母在 Python 使用的字符编码中占据连续的范围。 更方便的是，Python 已经通过以下方式公开了所需的转换`str.swapcase()`。 如果我们想了解底层算法而不是依赖库操作，我们可以检查一个字符是否位于`a`通过`z`或者`A`通过`Z`并将其移动两个案例之间固定的 ASCII 距离。 

暴力方法之所以有效，是因为每个字符都可以映射到其相反的大小写。 映射是一种固定转换的观察结果让我们可以用每个字符一个常量时间操作来代替对可能字母的搜索。 最终的算法仍然是 O(n)，但它具有尽可能最小的渐近复杂度，并且每个字符的工作量很少。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(52n) = O(n) | O(n) | 已接受，但不必要的工作 |
 | 最佳 | O(n) | 输出 | O(n) 已接受 |

 ## 算法演练

 1. 读取整个字符串并仅删除尾随换行符。 输入不包含空格，所以`strip()`在这里就足够了，尽管只删除`\n`也会起作用。 
2. 创建一个空结果字符串。 我们将为每个输入字符添加一个字符，因此输出长度与输入长度保持相同。 
3. 从左到右扫描输入。 对于每个字符，确定它是小写还是大写。 
4. 如果字符是小写，则将其转换为大写。 如果是大写，则将其转换为小写。 蟒蛇的`swapcase()`对每个字符精确执行此转换，并且由于保证输入包含字母字符，因此无需处理其他字符类别。 
5. 打印转换后的字符串。 所有字符的相对顺序不变，因为每个字符都是独立变换的。 

### 为什么它有效

 扫描期间的不变性是，在处理前 k 个字符后，结果完全包含这些相同 k 个字符的原始顺序的大小写切换版本。 当处理下一个字符时，`swapcase()`将大写字母更改为小写字母，将小写字母更改为大写字母，因此对于 k + 1 个字符，不变式仍然成立。 处理完最后一个字符后，不变量覆盖整个字符串，这意味着生成的字符串正是所需的输出。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    print(s.swapcase())

if __name__ == "__main__":
    solve()
```输入行被读取一次，与问题包含单个字符串的事实相匹配。`strip()`删除标准输入添加的换行符。 由于该语句保证字符串内没有空格，因此它不会意外删除有意义的空格。 

致电给`swapcase()`独立地将所需的变换应用于每个角色。 它还避免为大写和小写字母编写单独的分支。 直接打印结果字符串，因此不存在可能引入差一错误的索引或边界条件。 

另一种实现可以使用`ord()`和`chr()`手动添加或减去 ASCII 大小写差异，但这会使解决方案更长，而不会提高其渐近复杂性。

 此示例在同一字符串中练习两个方向的转换。 该不变量在每个字符之后都成立，因为每个处理的前缀已经完全具有所需的大小写切换。 

对于第二个例子，考虑`aBcD`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个字符都被处理一次。 |
 | 空间| O(n) | 转换后的字符串有 n 个字符。 |

 线性时间界限是最佳的，因为输入本身包含 n 个字符，并且必须考虑每个字符。 该算法不使用与输出字符串以外的任何内容成比例的辅助数据结构，因此它也适合问题允许的任何实际输入大小的 256 MB 内存限制。 

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    s = input().strip()
    print(s.swapcase())

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    out = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = out

    try:
        solve()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

    return out.getvalue()

# Provided sample
assert run("HeLlO\n") == "hElLo\n", "sample 1"

# Minimum-size input
assert run("A\n") == "a\n", "single uppercase character"

# All lowercase
assert run("abcdef\n") == "ABCDEF\n", "all lowercase characters"

# All uppercase
assert run("ABCDEF\n") == "abcdef\n", "all uppercase characters"

# Mixed boundary characters
assert run("aAzZ\n") == "AaZz\n", "first and last letters of both cases"

# Large input
large = "a" * 100000
assert run(large + "\n") == ("A" * 100000) + "\n", "large input"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 |`A`|`a`| 最小尺寸输入和大写转换 |
 |`abcdef`|`ABCDEF`| 每个字符都需要小写到大写的转换 |
 |`ABCDEF`|`abcdef`| 每个字符都需要大写到小写转换 |
 |`aAzZ`|`AaZz`| 字母边界和混合大小写 |

 ## 边缘情况

 对于单字符输入`A`，该算法读取一个字符，调用`swapcase()`，并获得`a`。 因此输出是`a`。 对于第一个或最后一个位置没有特殊处理，因为每个位置都遵循完全相同的规则。 

对于全小写输入`abc`，每个字符独立切换。 中间状态是`A`， 然后`AB`， 然后`ABC`，给出最终输出`ABC`。 这捕获了一个意外地只处理大写字母的实现。 

对于全大写输入`ABC`，同样的过程产生`abc`。 这会捕获相反的错误，即实现转换小写字符但保持大写字符不变。 

对于混合输入`aBcD`，字符变成`A`,`b`,`C`， 和`d`，生产`AbCd`。 这证实了该算法并不假设所有字符都具有相同的原始大小写。 

对于边界输入`aAzZ`，第一个小写字母变为`A`，第一个大写字母变为`a`，最后一个小写字母变成`Z`，最后一个大写字母变成`z`。 确切的输出是`AaZz`。 测试字母表的两端很有用，因为基于 ASCII 的手动实现通常会引入不正确的偏移或边界条件。 

对于包含 100000 个副本的大型输入`a`，每个字符被处理一次，结果包含 100000 个副本`A`。 这证实了该实现执行线性工作而不是重复地重新扫描字符串。
