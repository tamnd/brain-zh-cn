 ## 解决方案
 ## 问题理解

 我们得到了我们控制的玩家，或者`X`或者`O`，其次是当前的 3 x 3 Tic-Tac-Toe 棋盘。 空单元格由空格表示。 我们需要确定是否至少有一个空单元格，放置我们的标记会立即在一行、一列或对角线上创建三个相等的标记。 

例如，与玩家`X`和董事会```
X OX  O X
```放置`X`在右中单元格中给出```
X OX XO X
```哪个完成了主对角线？ 不，主对角线已经是`X X X`才考虑了中心，所以这一招获胜。 

板子尺寸固定只有3×3，没有大的`n`隐藏在输入中，因此渐近复杂度在这里不如使获胜条件正确重要。 即使是检查每个空单元格并检查 8 个可能获胜行的方法也很小：最多有 9 个候选移动，每个移动需要检查 8 条线，最多进行 72 条线检查。 对于这种输入大小，二次或三次方法是完全安全的。 

棘手的部分不是性能，而是正确解释棋盘。 

一个边缘情况是已经完成的一行。 为了```
XXXXOO
```正确的输出是`Yes you can.`因为`X`可以在任何空单元格中放置一个标记，但更重要的是，如果粗心的实现仅检查具有恰好两个现有标记的单元格，则可能无法识别玩家已经获胜。 通常对该任务的预期解释是是否存在获胜动作，因此最安全的实现是直接测试候选动作。 

另一个边缘情况是对角线获胜。 为了```
OXOX O X
```放置`O`右下角完成了主对角线，所以输出是`Yes you can.`。 仅默默检查行和列的实现会错过这种情况。 

第三种边缘情况是反对角线上的获胜棋步。 为了```
XX O O   X
```放置`X`右上角的单元格给出了反对角线`X X X`，所以答案是`Yes you can.`。 两条对角线都必须处理。 

Codeforces 显示的示例包含一个尾随`|`在每个板行之后。 这是语句显示的董事会表示的一部分，因此下面的实现删除了`|`读取一行并将空格保留为空单元格时。 

## 方法

 最直接的暴力解决方案是尝试每个空方块。 对于每个候选方格，将我们的标记暂时放置在那里，并检查所有三行、所有三列和两条对角线。 如果这八行中的任何一行完全由我们的标记组成，则该举动获胜。 

这已经够快了。 最多有 9 种可能的走法，正好有 8 条获胜线，因此最坏的情况最多执行 72 条线检查。 每条线仅包含 3 个电池，最多可进行 216 个单独的电池检查。 由于棋盘始终为 3 x 3，因此这实际上是恒定时间。 

我们可以通过观察移动只能影响行、列以及可能影响穿过所选单元格的一两条对角线来进一步简化实现。 我们可以直接询问某个获胜行当前是否恰好包含我们的两个标记和一个空单元格，而不是在每次移动后检查所有八行。 那么那个空单元格就是获胜的一步。 

井字游戏中只有八种可能的获胜线。 我们检查每一个，计算标记和空单元格，并接受是否一行恰好包含两个标记和一个空单元格。 这避免了修改电路板并使条件特别明确。 

暴力解决方案已被接受，因为输入是固定的 3 x 3 板。 第二种方法更可取，因为它直接表达获胜举动的数学条件并且需要操纵的状态较少。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(1)，最多 216 个单元检查 | O(1) | O(1) | 已接受 |
 | 查看所有中奖线 | O(1)，8 条长度为 3 的线 | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取玩家的标记和棋盘的三行。 删除可能的尾随`|`从每一行中删除空格，但不要删除空格，因为空格代表空单元格。 
2. 列举八条获胜线：三行、三列、主对角线、反对角线。 每一个可能的井字游戏胜利都属于这些行中的一条。 
3. 对于每一行，计算有多少单元格包含我们的标记以及有多少单元格为空。 
4. 如果一行恰好包含我们的两个标记和一个空单元格，则该空单元格是合法的获胜动作。 打印`Yes you can.`立即地。 
5. 如果检查了所有八行都没有找到这样一行，则打印`No you can't.`。 

关键的不变量是，在处理八条获胜线的任何前缀之后，已经检测到属于这些处理线的每一个可能的一手获胜。 由于每次井字游戏获胜都是八条线之一，因此完成扫描就证明，当没有发现任何获胜动作时，就不存在获胜动作。 

## Python 解决方案```python
Pythonimport sysinput = sys.stdin.readline

def solve():    player = input().strip()
    board = []    for _ in range(3):        row = input().rstrip("\n")        if row.endswith("|"):            row = row[:-1]        board.append(row)
    lines = []
    for r in range(3):        lines.append([(r, 0), (r, 1), (r, 2)])
    for c in range(3):        lines.append([(0, c), (1, c), (2, c)])
    lines.append([(0, 0), (1, 1), (2, 2)])    lines.append([(0, 2), (1, 1), (2, 0)])
    for line in lines:        mine = 0        empty = 0
        for r, c in line:            if board[r][c] == player:                mine += 1            elif board[r][c] == " ":                empty += 1
        if mine == 2 and empty == 1:            print("Yes you can.")            return
    print("No you can't.")

if __name__ == "__main__":    solve()
```第一输入行标识哪个符号属于当前玩家。 我们将其保留为单个字符，因此以后的每次比较都很简单`board[r][c] == player`。 

每个板行的读取方式为`rstrip("\n")`而不是`strip()`。 这种区别很重要，因为`strip()`将删除前导空格和尾随空格，从而破坏有关空单元格的信息。 如果输入表示包含尾随`|`官方示例中显示，单独删除。 

八条获胜线由它们的三个坐标对表示。 前六条描述了三条水平线和三条垂直线，而后两条描述了对角线。 

对于每一行，`mine`计算当前玩家的分数并`empty`计算空格。 当这些计数达到时，就存在获胜的举动`2`和`1`。 第三个单元格必须是空的，可以用玩家的标记填充以创建连续的三个单元格。 

无需修改棋盘、撤消移动或搜索候选单元格。 这避免了暴力版本中最常见的实施错误，即在测试下一个候选者时将临时移动留在棋盘上。 

Python 整数在这里不能溢出，并且所有索引都明确限制为`0`,`1`， 和`2`。

 ## 边缘情况

 一排有两个玩家标记和一个空单元格是最简单的获胜案例。 为了```
XXX OO
```第一行包含两个`X`标记和一个空格。 算法记录`mine = 2`和`empty = 1`，所以它立即返回`Yes you can.`。 这会捕获意外要求空单元格位于特定列中的实现。 

对于对角线情况，考虑```
OOXX O
```主对角线是`O O space`。 当算法到达该线时，其计数为`mine = 2`和`empty = 1`，因此右下角的单元格被确定为获胜棋步。 仅检查水平线和垂直线的解决方案将错误地返回`No you can't.`。 

对角线必须单独处理。 和```
X O  XO  X
```反对角线包含`X X space`从右上角到左下角。 该算法明确包含坐标`(0, 2)`,`(1, 1)`， 和`(2, 0)`，因此它可以找到获胜的着法，而不依赖于代码中其他地方隐藏的特殊情况。 

最后，样本的尾随`|`字符需要仔细的输入处理。 为了```
XXOX|XO |O X|
```解析器仅删除最后的`|`，使每行内的空格保持不变。 生成的板正好是三个单元格宽，第三列包含`X`、一个空格，以及`X`，这给出了所需的获胜着法。 输出是`Yes you can.`。
