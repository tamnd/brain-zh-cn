 ## 解决方案
 ## 问题理解

 任务是判断一个矩形整数数组是否具有两种镜像对称性。 水平对称意味着一行必须与距相对边缘相同距离的行匹配。 垂直对称意味着一列必须与距相对边缘相同距离的列相匹配。 当行数或列数为奇数时，中心行或中心列直接位于其对应的轴上，因此不需要与该轴的另一行或列进行比较。 官方声明要求`True`仅当两个对称性都成立时。 

如果数组有`R`行和`C`列，有`R * C`要读取的值，因此任何解决方案至少需要`O(RC)`只是检查输入的时间。 已发表的声明没有提供明确的数字上限`R`和`C`; 它给出了 1 秒的时间限制和 256 MB 的内存限制。 这意味着没有任何理由去考虑比单元数量线性慢的算法。 随着矩阵的增长，对单元格的二次搜索或重复比较整行和整列将变得不必要的昂贵。 一个`O(RC)`扫描是自然目标。 

第一个边缘情况是单个单元格。 用于输入```
1 1
7
```正确的输出是`True`。 轴两侧的单元都不能与中心不一致。 如果粗心的实现期望每行和每列都有一个不同的镜像伙伴，则可能会错误地拒绝它。 

第二种边缘情况是奇数大小的矩阵，其中心行在水平方向上不相关，但仍需要检查垂直对称性。 例如，```
3 3
1 0 1
2 3 4
1 0 1
```具有匹配的顶行和底行，但中间行不是垂直对称的，因为`2 != 4`，所以正确的输出是`False`。 简单地忽略整个中间行（因为它位于水平轴上）的实现将错误地打印`True`。 

同样的区别也适用于中心柱。 例如，```
3 3
1 2 1
0 3 0
1 4 1
```具有垂直对称性，但中间列的顶部和底部单元格不同，因此水平对称性失败，答案是`False`。 中间一列仅在垂直反射时被忽略，水平反射则不被忽略。 

最后，矩形数组不能被视为方阵。 例如，```
2 3
1 2 1
1 2 1
```在两个轴上对称并且应该产生`True`。 行计数和列计数具有单独的镜像索引，因此使用行数来计算两个反射坐标很容易产生索引错误。 

## 方法

 直接的方法是读取整个矩阵，并且对于每个单元格`(i, j)`，将其与其水平反射位置进行比较`(R - 1 - i, j)`及其垂直反射位置`(i, C - 1 - j)`。 如果任何比较失败，立即给出答案`False`; 如果所有比较都成功，则答案是`True`。 这是正确的，因为这两个等式正是所需水平和垂直对称性的定义。 

如果这个直接版本检查所有的两个条件`R * C`单元格，其最坏情况的值比较次数恰好是`2RC`。 该声明没有给出使该方法渐近无效的界限，并且事实上`O(RC)`是最优的，因为矩阵本身包含`RC`价值观。 所以这里的暴力扫描并没有错，也没有根本上太慢。 它的弱点是它执行相同的对称性比较两次，因为当访问镜像单元时，也会重复将单元与其镜像进行比较。 

有用的观察是每次反射都会将细胞配对。 对于水平对称性，将第一行与最后一行进行比较就足够了，因为从最后一行到第一行的反向比较将包含完全相同的信息。 这同样适用于每对行。 因此我们只需要第一个`R // 2`用于水平检查的行。 同样，只有第一个`C // 2`垂直检查需要列。 当中心行或列的尺寸为奇数时，它自然会从这些循环中消失。 

优化的扫描执行`floor(R / 2) * C + R * floor(C / 2)`最坏情况下的比较。 它仍然有`O(RC)`复杂性，但它避免了多余的工作并直接表达哪些对实际需要检查。 更重要的是，它可以自然地处理奇数维度，无需特殊情况。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(RC) | O(RC) | 已接受，但多余 |
 | 最佳 | O(RC) | O(RC) | 已接受 |

 必须存储矩阵，因为反射单元可能位于输入中的任何位置，因此渐近最优解仍然使用`O(RC)`具有简单实现的内存。 

## 算法演练

 1. 阅读`R`和`C`，然后存储`R x C`矩阵。 我们需要随机访问单元格及其反射单元格，因此保持矩阵使每次比较时间恒定。 
2. 仅检查行的水平对称性`i`在哪里`0 <= i < R // 2`。 比较`a[i][j]`和`a[R - 1 - i][j]`对于每一列`j`。 这些正是通过反射配对的两行，每对都被访问一次。 
3. 仅检查列的垂直对称性`j`在哪里`0 <= j < C // 2`。 比较`a[i][j]`和`a[i][C - 1 - j]`对于每一行`i`。 同样，每个反射列对都被访问一次。 
4. 打印`False`当任何比较不同时立即进行。 一对不匹配就足以破坏所需的对称性，因此继续下去只会浪费时间。 
5. 如果两个循环都完成且没有不匹配，则打印`True`。 每个行对在水平方向上一致，每个列对在垂直方向上一致，这正是所需的条件。 

为什么它有效：水平循环期间的不变性是到目前为止处理的每个行对在垂直位置保存下都是相同的。 由于循环只覆盖每对不同的行一次，因此整个矩阵在完成时是水平对称的。 垂直循环为每对柱建立了类似的属性。 中心行和列不包含在其相应的循环中，因为它们反映自身。 因此，在两个循环完成后，每个所需的反射相等都成立，因此算法无法返回`True`对于不对称矩阵。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    R, C = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(R)]

    # Horizontal symmetry.
    # Only one row from each mirrored pair needs to be checked.
    for i in range(R // 2):
        ri = R - 1 - i
        for j in range(C):
            if a[i][j] != a[ri][j]:
                print("False")
                return

    # Vertical symmetry.
    # Only one column from each mirrored pair needs to be checked.
    for j in range(C // 2):
        cj = C - 1 - j
        for i in range(R):
            if a[i][j] != a[i][cj]:
                print("False")
                return

    print("True")

if __name__ == "__main__":
    solve()
```第一个循环实现演练的水平部分。`range(R // 2)`故意排除中间行时`R`很奇怪。 对于偶数行，它恰好覆盖每个镜像对的第一行。 

反射的行是`R - 1 - i`，因为 Python 使用从零开始的索引。 例如，有五行，行`0`反映到行`4`， 排`1`反映到行`3`，和行`2`反映到自己身上。 由于循环之前停止`i == 2`，自我反思无需比较。 

第二个循环与交换行和列的想法相同。`C - 1 - j`给出反射列，同时`range(C // 2)`避免检查中心列时`C`很奇怪。 

该函数在第一次不匹配后立即返回。 Python 中不存在整数溢出问题，并且该实现不执行除索引计算之外的算术。 输出字符串也与所需的大小写完全匹配：`True`和`False`。

## 边缘情况

 对于单细胞情况```
1 1
42
```

`R // 2`和`C // 2`都为零，因此两个比较循环都不执行。 算法进入最终阶段`True`。 这是正确的，因为唯一的单元位于两个对称轴上并且没有明显的反射伙伴。 

对于不对称中排情况```
3 3
1 0 1
2 3 4
1 0 1
```水平循环仅检查行`0`和`2`，哪个匹配。 然后检查列的垂直对称性`0`和`2`横跨所有三行。 中间一行，比较的是`2 != 4`，所以算法返回`False`。 这说明了为什么不能简单地从整个问题中丢弃奇怪的中心行。 

对于不对称中柱情况```
3 3
1 2 1
0 3 0
1 4 1
```垂直循环检查列`0`和`2`，每一行都匹配。 水平循环已经比较行`0`带行`2`，并在列`1`它发现`2 != 4`。 结果是`False`。 中心列与垂直反射无关，但其条目仍然参与水平反射。 

对于长方形的情况```
2 3
1 2 1
1 2 1
```水平循环比较行`0`带行`1`，并且每个值都匹配。 垂直循环比较列`0`带柱`2`，而列`1`是中心列并被跳过。 结果是`True`。 这证实了反射行索引必须使用`R - 1 - i`并且反射列索引必须使用`C - 1 - j`独立。
