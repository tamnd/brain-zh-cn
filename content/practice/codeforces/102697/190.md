 ## 解决方案
 ## 问题理解

 我们有一个城镇，里面有 (n) 个人。 对于每个人，输入都会给出他们的姓名以及感染他们的人的姓名。 恰好有一个人有`OTHER`作为他们的来源，这意味着他们的感染来自城镇外。 

如果一个人直接感染了至少三个人，则被称为超级传播者。 任务是按照人们在输入中出现的顺序打印每个超级传播者。 如果没有人感染三个或更多人，我们会打印`NONE`。 

关键细节是该问题询问**直接**感染。 如果爱丽丝感染了鲍勃，而鲍勃感染了谢丽尔，那么爱丽丝就不会被认为感染了谢丽尔。 我们只计算有多少输入记录将特定人员命名为其直接来源。 

语句中唯一明确的数值约束是 (n) 是正整数。 (n) 没有规定上限，因此算法应该避免任何随人数呈二次方增长的情况。 自然目标是单次遍历 (n) 条记录。 对于 (n) 条记录，(O(n^2)) 方法可能需要大约 (n^2) 次名称比较，而 (O(n)) 方法仅处理每个记录固定次数。 

有几个小情况可能会导致粗心的实施失败。 

考虑一个仅包含从外部感染的人的城镇：```
1
Alice OTHER
```正确的输出是：```
NONE
```没有指定 Alice 的感染记录，因此 Alice 没有感染任何人。 一个意外地计算了的实现`OTHER`记录为由 Alice 引起的感染会产生错误的结果。 

考虑由同一个人感染的三个人：```
4
Alice OTHER
Bob Alice
Cheryl Alice
Darryl Alice
```正确的输出是：```
Alice
```Alice 正好有 3 个直接受害者，因此阈值是包容性的。 测试`count > 3`而不是`count >= 3`会错误地拒绝她。 

最后，考虑一条链：```
4
Alice OTHER
Bob Alice
Cheryl Bob
Darryl Cheryl
```正确的输出是：```
NONE
```每个人都感染了另外一个人。 尝试对某个人下游可到达的每个人进行计数的解决方案会错误地对 Alice 进行分类，即使该定义仅计算直接传输。 

## 方法

 最直接的暴力解决方案是检查每个人并扫描所有（n）条感染记录，以计算该人的名字作为来源出现的次数。 这是正确的，因为每个直接感染作为输入记录只出现一次，因此匹配源名称的数量正是该人的直接传播数量。 然而，对每个人进行全面扫描需要 (O(n^2)) 次比较。 对于 (n) 条记录，最坏的情况是 (n^2) 次操作，随着输入的增长，这很快就会变得不切实际。 

输入的结构为我们提供了一种更简单的计数方法。 每条记录都有以下形式`victim source`，与超级传播者相关的唯一信息是源字段。 每当出现来源名称时，我们就可以立即增加该人的感染计数。 字典给出了此更新的恒定预期时间，因此整个输入可以一次性处理。 

输出顺序需要单独注意。 字典迭代顺序不应用作决定所需顺序的机制。 相反，我们保留人们的原始输入顺序，并按该顺序执行最终过滤。 这直接匹配语句，并且无论字典如何实现都有效。 

暴力方法之所以有效，是因为它根据完整的输入反复重建每个人的受害者数量。 它失败了，因为它为每个人重复了几乎相同的工作。 观察到每次感染都会导致一个源计数，因此我们可以将所有这些重复扫描汇总到一次扫描中。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(n^2)) | (O(n)) | (O(n)) | 对于大 (n) 来说太慢 |
 | 最佳| (O(n)) 预期 | (O(n)) | (O(n)) | 已接受 |

 ## 算法演练

 1.读取(n)条，然后对(n)条感染记录进行一一处理。 按照原始输入顺序存储每个人的姓名，因为最终答案必须保留此顺序。 
2. 对于每条记录`person source`，增加与关联的计数`source`，除非当`source`是`OTHER`。`OTHER`代表的是镇外的来源，因此不能被报告为当地超级传播者。 
3. 处理完所有记录后，按原始输入顺序扫描人员。 当一个人的累计计数至少为 3 时，他就是超级传播者，因此只要计数达到该阈值，就附加他们的名字。 
4. 如果结果列表为空，则打印`NONE`。 否则，将每个存储的超级传播器打印在其自己的行上。 

将计数与输出分开的原因是，当读取自己的输入记录时，一个人的计数不一定是完整的。 某人可以稍后在输入中显示为来源，因此在阅读所有记录之前确定某人是否符合资格可能会产生不正确的结果。 

### 为什么它有效

 处理输入的任何前缀后，名称的字典计数等于处理的源是该名称的感染记录的数量。 每条记录恰好代表一次直接感染，因此每个直接受害者都向正确的源贡献了一个增量。 处理完所有 (n) 条记录后，每个人的计数就是他们的直接受害者总数。 使用条件过滤这些计数`>= 3`因此准确选择超级传播者。 由于最终扫描遵循原始输入顺序，因此输出顺序也是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    people = []
    infected_by = {}

    for _ in range(n):
        person, source = input().split()
        people.append(person)

        if source != "OTHER":
            infected_by[source] = infected_by.get(source, 0) + 1

    answer = []

    for person in people:
        if infected_by.get(person, 0) >= 3:
            answer.append(person)

    if answer:
        sys.stdout.write("\n".join(answer) + "\n")
    else:
        sys.stdout.write("NONE\n")

if __name__ == "__main__":
    solve()
```这`people`list 准确保留名称在输入中出现的顺序。 我们需要这个，因为该语句指定输入顺序而不是字母顺序或任何其他顺序。 

这`infected_by`字典存储每个源的直接感染计数。`get(source, 0)`干净地处理这两种情况：第一次看到的源从零开始，而现有的源又接收到一个受害者。 

这`OTHER`检查必须在更新字典之前进行。`OTHER`不是城镇居民，因此不可能成为该问题的超级传播者。 

最后的循环使用`infected_by.get(person, 0)`因为很多人可能永远不会作为消息来源出现。 将缺失的名称视为计数零正是我们所需要的。 

Python 中不存在整数溢出问题。 最大可能的计数是 (n)，Python 整数直接处理它。 该实现还避免了嵌套循环，这是暴力解决方案中的主要性能问题。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O(n)) 预期 | 每条记录都会导致一次字典更新，然后对 (n) 个人进行一次扫描。 |
 | 空间| (O(n)) | (O(n)) | 输入顺序和字典各自最多可以包含 (n) 个名称。 |

 该算法仅对每个输入记录执行恒定数量的预期时间字典工作以及一次额外的线性扫描。 由于该语句没有给出超出 (n > 0) 的上限，因此线性时间是适当的目标，并且避免了重复扫描整个输入的二次行为。

 ## 边缘情况

 第一个边缘案例是只有外部感染源的城镇：```
1
Alice OTHER
```该算法将 Alice 存储在`people`，但跳过`OTHER`更新时的来源`infected_by`。 因此，爱丽丝的隐式计数为零。 最终检查失败`>= 3`条件，所以输出是`NONE`。 

第二个边缘情况是精确阈值：```
4
Alice OTHER
Bob Alice
Cheryl Alice
Darryl Alice
```源 Alice 的三个记录将她的计数从零增加到一，然后是二，然后是三。 最终扫描看到`infected_by["Alice"] == 3`，所以爱丽丝被打印出来。 这抓住了使用严格的常见错误`> 3`比较。 

第三种边缘情况是传输链：```
4
Alice OTHER
Bob Alice
Cheryl Bob
Darryl Cheryl
```字典结尾为`{Alice: 1, Bob: 1, Cheryl: 1}`。 Alice的下游有两个人，但只有Bob是被Alice直接感染的。 由于每次计数都是 1，因此输出为`NONE`。 这证实了该算法匹配直接感染定义，而不是计算图可达性。 

最后的边缘情况涉及输出排序：```
8
Zoe OTHER
Amy Zoe
Bob Zoe
Cara Zoe
Dan Amy
Eve Amy
Fox Amy
Gus Bob
```佐伊（Zoe）受到三次直接感染，艾米（Amy）也受到三次直接感染。 两者都有资格。 他们的名字按该顺序出现在输入中，因此最终扫描会产生：```
Zoe
Amy
```对名称进行排序可能会给出不同的顺序，这就是为什么显式保留原始输入序列比依赖字母或字典顺序更安全。
