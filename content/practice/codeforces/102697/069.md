 ## 解决方案
 ## 问题理解

 任务是独立旋转小写单词的每个字符。 对于位置处的角色`i`，输入给出整数移位`k[i]`。 正移位使字符在字母表中向前移动，而负移位则使字符向后移动。 字母表是循环的，所以移动过去`z`继续于`a`，并在之前移动`a`继续于`z`。 

例如，旋转`a`经过`5`给出`f`，同时旋转`a`经过`-5`给出`v`。 转变不一定是在`-25`和`25`， 所以`a`移动了`30`是一样的`a`移动了`4`, 给予`e`。 

第一个输入行是单词本身。 第二行每个字符包含一个整数，该整数位于位置`i`描述该角色应该移动多远。 输出是应用所有旋转后得到的单词。 

可用于此问题的语句未指定字长或旋转值的数字上限。 时间限制为 1 秒，内存限制为 256 MB。 无论缺少显式边界如何，预期的解决方案都应该处理每个字符恒定的次数。 与移位幅度成正比的算法是不安全的，因为单个移位可能远大于 26。字母表只有 26 个位置，因此每个移位首先可以对 26 进行模减。 

第一个边缘情况是负偏移。 例如，```
a
-5
```产生```
v
```粗心的实现仅使用`ord(c) + k`直接转换回字符可以产生小写字母之外的字符。 对于负值，模运算也必须正确工作。 

第二种边缘情况是大于一个完整字母表的移位。 例如，```
a
30
```产生```
e
```因为`30 mod 26 = 4`。 重复移动角色 30 个位置是不必要的，并且对于非常大的移位来说变得特别低效。 

当移位恰好落在字母表边界上时，就会发生第三种边缘情况。 例如，```
z
1
```产生```
a
```字符位置必须以 26 为模进行计算，而不是固定到`z`。 

第四种边缘情况是跨越字母表开头的负移位。 例如，```
b
-3
```产生```
y
```这捕获了尝试使用单独的减法分支处理负位置但忘记了环绕的实现。 

## 方法

 直接的暴力方法实际上一次执行一个角色移动。 对于一个角色`c`并转变`k`，我们可以重复增加或减少它的字母位置，直到`|k|`已经进行了动作。 这是正确的，因为每个单独的运动都准确地代表了循环字母表中的一步。 

问题是这项工作取决于偏移的幅度而不是输入的大小。 如果单词有长度`N`最大的绝对偏移是`K`，最坏的情况需要`O(NK)`个人动作。 例如，如果有`100,000`角色和每一次转变都有幅度`10^9`，这需要最多`10^14`人物动作。 这远远超出了 1 秒解决方案的执行范围。 

关键的观察结果是，在 26 个字符的字母表中移动是周期性的。 向前移动 26 次后，角色就回到了起始位置。 向后移动26次也是如此。 因此，一个转变`k`具有完全相同的效果`k mod 26`。 

一旦移位以 26 为模减少，我们就可以将当前字符转换为 0 到 25 之间的数字，添加减少的移位，然后将结果以 26 为模。这会立即给出最终的字母表位置，无论原始移位有多大或负数。 

蛮力之所以有效，是因为每个动作都是模拟的，但当变化很大时就会失败。 通过观察字母表每 26 个位置重复一次，我们可以用一次模算术运算来替换任意数量的移动。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(NK)`在哪里`K = max( | shift[i] | )`|`O(N)`| 对于大班次来说速度太慢 |
 | 最佳 |`O(N)`|`O(N)`| 已接受 |

 ## 算法演练

 1. 读单词和移位顺序。 每个字符都有一个转变，因此索引处的字符`i`必须搭配`shift[i]`。 
2. 对于每个字符，使用以下命令将其转换为从零开始的字母位置`ord(c) - ord('a')`。 因此`a`变成`0`,`b`变成`1`， 和`z`变成`25`。 
3. 减少相应的移位模 26。只有余数很重要，因为 26 个位置构成了字母表的一个完整循环。 
4. 将减少的移位添加到原始字母表位置，并对结果取模 26。这可以处理正旋转和负旋转，同时将结果保持在范围内`0`通过`25`。 
5. 使用以下命令将结果字母位置转换回小写字符`chr(position + ord('a'))`。 
6. 将生成的字符附加到输出列表，并在处理完所有字符后加入该列表。 构建列表并加入它可以避免重复构建越来越大的字符串。 

### 为什么它有效

 对于每个字符，其位置以模 26 表示。`k`将该位置更改为`(position + k) mod 26`。 由于相差 26 倍数的两个移位产生相同的位置，因此替换`k`经过`k mod 26`不会改变结果。 该算法独立地将这种转换应用于每个字符，因此每个输出字符都是其相应旋转所需的字符。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    shifts = list(map(int, input().split()))

    base = ord('a')
    result = []

    for c, shift in zip(s, shifts):
        position = ord(c) - base
        position = (position + shift) % 26
        result.append(chr(position + base))

    print(''.join(result))

if __name__ == "__main__":
    solve()
```第一行读取的单词不带尾随换行符。 第二行被分割成整数，以便每个值都可以与同一索引处的字符配对。 

循环使用`zip(s, shifts)`使字符和旋转之间的对应关系明确。 对于每一对，`ord(c) - ord('a')`将字符更改为 0 到 25 之间的数字。 

蟒蛇的`%`运算符以此处有用的方式处理负操作数。 例如，`(-3) % 26`是`23`，所以位置处的字符`1`，代表`b`，变成`(1 - 3) % 26 = 24`，这代表`y`。 不需要特殊的负移位分支。 

添加移位后应用模运算，因此结果位置始终在 0 到 25 之间。Python 中不存在整数溢出问题，即使移位非常大，算术也保持恒定时间。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(N)`| 每个字符及其相应的移位都被处理一次。 |
 | 空间|`O(N)`| 输出字符在连接之前被存储。 |

 该算法不依赖于移位的幅度，因为每个移位都是通过一次模运算来处理的。 这使得它即使在输入包含非常大的正旋转值或负旋转值时也适用。 256 MB 内存限制也足以存储单词及其输出。

 ## 边缘情况

 对于负位移情况，```
a
-5
```字符位置开始于`0`。 该算法计算`(0 - 5) % 26 = 21`，位置 21 是`v`。 因此输出是`v`。 不需要对负值进行特殊处理，因为模算术直接表示环绕。 

对于大于一个字母表的移位，```
a
30
```计算出的位置是`(0 + 30) % 26 = 4`，对应于`e`。 该算法为此轮班执行的工作量与为`4`。 

对于前向环绕，```
z
1
```位置是`(25 + 1) % 26 = 0`, 给予`a`。 模运算正是将结果从字母表末尾移动回其开头的操作。 

对于向后环绕，```
b
-3
```位置是`(1 - 3) % 26 = 24`, 给予`y`。 假设中间位置必须保持非负的手动编写的实现很容易使这种边界情况出错，而模块化公式可以直接处理它。 

该示例本身将其中几种情况组合到一个输入中。 转变`54`测试大于 26 的值，`-80`测试一个大的负值，结果字母确认每次旋转都应用于匹配索引处的字符。
