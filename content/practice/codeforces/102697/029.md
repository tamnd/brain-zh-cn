 ## 解决方案
 # 问题理解

 该问题给出了一个字符串，代表足球评论员在进球后伸长的庆祝动作。 这个词的开头和结尾与普通词“目标”类似，但是`o`中间的字符可以根据播音员喊的时间延长。 任务是准确数出有多少个`o`字母出现在整个记录的反应中。 

输入包含一个字符串，因此唯一需要的操作是扫描其字符。 这些限制允许直接线性通过字符串。 即使字符串非常大，`O(n)`解决方案仅对每个字符执行一次简单的检查，而重复搜索或修改字符串的较慢方法会增加不必要的工作。 

主要的边缘情况来自假设单词始终具有固定长度或仅手动计算中间部分。 例如，输入：```
goal
```有输出：```
1
```假设总是有多个解决方案`o`角色将在最短的有效反应中失败。 

另一种情况是：```
goooooooooal
```与输出：```
9
```数量`o`字符不固定，因此检查特定模式，例如`"goal"`或者仅计算硬编码范围内的位置会产生错误的答案。 

最后一个常见错误是忘记输入应该被视为字符串而不是将其转换为另一种类型。 角色本身就携带着信息，并且每一次出现`o`必须计算。 

## 方法

 蛮力思想已经接近最优解，因为问题没有需要高级算法的隐藏结构。 一种直接的方法是检查播音员反应中的每个角色，并在当前角色出现时增加计数器。`o`。 这是有效的，因为每个`o`恰好为所需答案贡献了一个字符，其他字符都不重要。 

唯一可能的低效方法是重复搜索字符串以查找出现的`o`或者在计数时构建许多临时字符串。 在最坏的情况下，如果字符串长度为`n`，重复扫描整个字符串可以达到`O(n²)`操作，这是不必要的。 

关键的观察是答案仅取决于单个角色。 无需了解字母的位置、验证单词结构或模拟播音员。 一次从左到右的遍历就足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从输入中读取反应字符串。 该字符串是完整的转录，因此应考虑每个字符。 
2. 将计数器初始化为零值。 该变量将存储多少个`o`到目前为止，角色已经出现。 
3. 一次遍历字符串一个字符。 每当当前字符是`o`，将计数器加一。 字符如`g`,`a`， 和`l`不影响结果。 
4. 打印最终计数器值。 遍历完成后，计数器代表了确切的数量`o`反应中的字母。 

为什么它有效：

 不变的是，处理完字符串的任何前缀后，计数器等于`o`该前缀内的字符。 最初前缀为空且计数器为零，因此不变量为真。 当处理一个新字符时，计数器会在该字符被处理时准确地发生变化。`o`，这使得不变量保持为真。 处理完整个字符串后，前缀就是整个输入字符串，因此计数器就是所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    print(s.count('o'))

if __name__ == "__main__":
    solve()
```该解决方案将整个反应读取为字符串，因为字符本身就是我们需要分析的数据。 

Python 的内置`count`方法执行算法中描述的相同线性扫描。 它检查每个字符一次并返回目标字符出现的次数。 

使用`strip()`删除输入添加的换行符，而不影响反应中的字母。 没有数值计算，因此不必担心整数溢出。

 ## 边缘情况

 为了尽可能短的反应：```
goal
```该算法读取四个字符。 计数器仅在到达第二个字符时增加一次，然后保持不变`a`和`l`。 最终输出为：```
1
```这可以防止由于假设播音员必须始终重复元音而导致的错误。 

对于一个漫长的庆祝活动：```
goooooooooal
```该算法没有特殊对待中间部分。 它只是访问每个位置并增加每个位置的计数器`o`，产生精确的计数。 这避免了关于播音员扩展单词的次数的硬编码假设。 

对于仅包含元音的字符串：```
oooo
```每个处理过的字符都会使计数器递增。 结果是：```
4
```这证实了该解决方案计算出现次数，而不是依赖于单词“goal”周围的字母。
