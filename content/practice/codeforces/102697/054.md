 ## 解决方案
 ## 问题理解

 我们收到两个日历日期。 第一个日期代表今天，第二个日期代表预定的会议。 每个日期都写为月份名称、日期数字和年份，例如`July 5, 2019`。 

任务是确定两个日期之间相隔的天数。 如果两个日期相同，则会议为今天。 如果会议日期较早，我们需要报告会议晚了多少天。 否则，我们会报告距离会议还剩多少天。 声明明确表示不需要考虑闰年。 

这里没有大型数组、图表或重复的测试用例。 输入恰好包含两个日期，因此即使是对较小的固定月份数的线性扫描也是有效的恒定时间。 因此，一秒的限制就足够了。 主要挑战不是性能，而是将人类可读的日期转换为可以安全比较和减去两个日期的表示形式。 

第一个边缘情况是平等。 例如，```
January 10, 2020January 10, 2020
```产生```
It is today
```如果粗心实施，仅检查会议日期是否晚于今天，否则将其视为过去的日期，则会错误地报告会议迟到了 1 天或 0 天。 

第二个极端情况是下个月的会议。 例如，```
January 31, 2020February 1, 2020
```相差一天。 仅计算天数之间的差异会产生`-30`，它完全忽略了月份边界。 

第三个边缘情况是上个月的一次会议。 例如，```
March 1, 2020February 28, 2020
```在问题的简化日历下晚了两天，因为 2 月有 28 天，闰年被忽略。 仅比较日期字段的解决方案会看到`28 > 1`并可能错误地得出会议是在未来举行的结论。 

第四个边缘情况是年份边界。 例如，```
December 31, 2019January 1, 2020
```相差一天。 比较月份和日期而不合并年份可以轻松颠倒顺序。 

## 方法

 直接的暴力方法将从第一个日期开始，重复前进一天，直到到达会议日期，或者在会议已经发生时重复后退。 这是正确的，因为每次转换都恰好代表一个日历日。 但是，其运行时间取决于日期间隔的天数。 由于该问题没有发布输入中年份的数值界限，因此该方法没有有用的固定上限，并且可能需要粗略地`365 * |year_difference|`迭代。 

有一个更清晰的表示。 由于所有月份的长度都是已知的并且可以忽略闰年，因此我们可以为每个日期分配一个绝对日数。 日期的绝对位置是其之前的完整年数，加上其之前所有完整月份所贡献的天数，再加上该日期在该月内的天数。 

例如，如果日期是 3 月 10 日，则 1 月和 2 月的所有日期都已在该日期之前。 一旦两个输入日期都转换为这种表示形式，整个日历计算就变成普通的整数减法。 

蛮力之所以有效，是因为一次前进一天可以准确地对日历进行建模，但它会失败，因为它每天执行一次操作。 观察到每个日期都可以映射到绝对日期索引，这让我们可以用两次转换和一次减法来替换潜在的数千或数百万个单独的转换。 

月份长度可以存储为`[31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]`。 由于明确排除了闰年，因此 2 月始终贡献 28 天。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(D) | O(1) | O(1) | 日期相距较远时速度太慢 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 这里`D`是两个日期之间的天数。 最佳解决方案仅检查十二个月的长度，这是持续的工作。 

## 算法演练

 1. 按日历顺序存储每个月的天数。 二月固定为 28，因为闰年​​不属于此问题。 
2. 将每个输入行解析为月份名称、日期和年份。 日期后面的逗号是文本格式的一部分，因此在将日期和年份转换为整数之前将其删除是最简单的方法。 
3. 将每个月份名称转换为其数字月份索引。 这让我们可以直接使用月份长度的数组。 
4. 将每个日期转换为绝对日数。 从日期之前的所有完整年份开始，贡献`year * 365`天。 然后添加当前月份之前所有完整月份的长度，最后添加当前日期。 
5. 从会议日期中减去第一个日期的绝对天数。 正结果表示会议在未来举行，零表示会议在今天举行，负结果表示会议已经过去。 
6. 根据差异的符号格式化答案。 为了积极的差异`d`，打印有`d`距会议召开还有几天。 对于零，打印`It is today`。 对于负差异，请使用`-d`作为迟到的天数。 

为什么这是有效的可以通过绝对日表示来体现。 每个普通年份正好贡献 365 天，每个月贡献固定的天数。 因此，相隔一个日历日的两个日期收到的绝对日数正好相差 1。 因此，减法恰好是分隔日期的天数。 它的符号也给出了时间顺序，所以最终的消息不能选择错误的情况。 

## Python 解决方案```python
Pythonimport sysinput = sys.stdin.readline
MONTHS = {    "January": 1,    "February": 2,    "March": 3,    "April": 4,    "May": 5,    "June": 6,    "July": 7,    "August": 8,    "September": 9,    "October": 10,    "November": 11,    "December": 12,}
DAYS_IN_MONTH = [    31, 28, 31, 30, 31, 30,    31, 31, 30, 31, 30, 31]

def parse_date(s):    month_name, rest = s.split()    day, year = rest.split(",")
    return MONTHS[month_name], int(day), int(year)

def to_day_number(date):    month, day, year = date
    total = year * 365
    for i in range(month - 1):        total += DAYS_IN_MONTH[i]
    total += day    return total

def solve():    first = input().strip()    meeting = input().strip()
    first_date = parse_date(first)    meeting_date = parse_date(meeting)
    first_day = to_day_number(first_date)    meeting_day = to_day_number(meeting_date)
    diff = meeting_day - first_day
    if diff == 0:        print("It is today")    elif diff > 0:        print(f"There are {diff} days until your meeting")    else:        print(f"Sorry you are {-diff} days late")

if __name__ == "__main__":    solve()
```

`parse_date`处理日期的确切文本结构。 分裂`July 5, 2019`给出`July`和`5, 2019`，之后在逗号处分割第二部分会生成数字日和年。`to_day_number`故意使用`year * 365`，而不是闰年感知公式。 这不是解决方案引入的近似值，它正是问题指定的日历模型。 

前几个月的循环使用`range(month - 1)`。 对于一月，执行零次，这是正确的边界条件，因为一月之前没有完整的月份。 对于三月，它处理一月和二月，即三月之前的两个完整月份。 

Python 整数不会溢出，因此对于大年份不需要特殊处理。 仅在两个日期都转换为同一坐标系后才执行减法，这避免了跨月或跨年的单独情况。

 ## 边缘情况

 对于相同的日期，请考虑：```
January 1, 1January 1, 1
```两个日期收到完全相同的绝对日数。 它们的差异为零，因此算法选择相等分支并打印`It is today`。 这种情况不需要特殊的日历计算。 

对于一个月边界，请考虑：```
January 31, 2020February 1, 2020
```一月贡献了 31 天。 第一个日期具有绝对位置`year * 365 + 31`，而第二个有`year * 365 + 31 + 1`，所以它们的差恰好是一。 这捕获了直接减去日期字段的实现。 

对于过去的会议，请考虑：```
March 1, 2020February 28, 2020
```3 月 1 日比 2 月的 28 天早，而 2 月 28 日仅比 2 月的前 27 天早。 绝对立场相差两位，会议的立场较小。 算法得到`diff = -2`，对显示的幅度取反，并打印`Sorry you are 2 days late`。 

对于一年边界，请考虑：```
December 31, 2019January 1, 2020
```第一个日期是 2019 年的最后一天，第二个日期是紧接的第二天。 年份贡献变化 365，而月份贡献重置，但绝对表示会自动吸收这两种变化。 由此产生的差异是一。 

最后，二月必须始终被视为 28 天。 该问题明确消除了闰年处理，因此`February 28, 2020`接下来是`March 1, 2020`此问题的日历模型中有一天的间隙。 添加闰年逻辑会引入该语句不要求的行为。
