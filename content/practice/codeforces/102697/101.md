 ## 解决方案
 ## 问题理解

 我们有一个（n \times n）方格代表一个大都市。 每个单元格包含一个从 0 到 9 的数字，这是该单元格中建筑物的高度。 当一栋建筑物的高度严格大于与其共享一侧或角落的所有建筑物的高度时，该建筑物被称为摩天大楼。 因此，每个单元最多有八个相关邻居。 任务是生成另一个（n \times n）网格，写入`Y`恰好在摩天大楼位置并且`N`其他地方。 原始问题使用 1 秒时间限制和 256 MB 内存限制。 

输入包含 (n)，后跟 (n) 个长度为 (n) 的字符串。 由于输入本身包含 (n^2) 个高度值，因此在 (O(n^2)) 时间内运行的算法是自然目标。 采用 (O(n^3)) 的解决方案已经执行了比需要检查的数据量多 (n) 倍的工作，而即使对于中等大小的网格，(O(n^4)) 也太昂贵了。 内存要求也很容易满足，因为网格仅包含 (n^2) 个小字符。 

第一个边缘情况是角或边界单元。 它没有八个邻居，因此我们不能访问网格之外的单元格。 例如：```
1
5
```唯一的建筑物没有相邻的建筑物，因此它比所有建筑物都空大。 正确的输出是：```
Y
```如果粗心的实现需要至少一个邻居，或者将缺失的邻居视为高度为 9，则会错误地打印`N`。 

第二个边缘情况是平等。 比较必须严格大于，而不是大于或等于。 例如：```
2
55
55
```每座建筑物都有一个高度相同的邻居，因此没有一座是摩天大楼。 正确的输出是：```
NN
NN
```一个实现使用`>=`会错误地将每个单元格标记为摩天大楼。 

第三种边缘情况是对角邻居。 对角单元格算作相邻单元格，即使它们不共享边缘。 例如：```
2
91
19
```左上角的建筑物高度为 9，比其他三座建筑物高，因此正确的输出是：```
YN
NY
```仅检查四个侧面邻居的实现恰好使该示例正确，但对角线关系在以下情况下变得决定性：```
2
19
91
```这里右上角和左下角的建筑物高度为 9，必须都标记`Y`。 当唯一的竞争建筑是对角线时，忽略对角线可能会默默地产生错误的答案。 

## 方法

 最直接的暴力解释是处理一栋建筑并将其高度与大都市中的所有其他建筑进行比较。 找到当前建筑物后，我们可以扫描所有（n^2）个单元格并检查其中是否有更高的单元格。 在最坏的情况下，对所有 (n^2) 栋建筑物执行此操作需要进行 (n^2 \cdot n^2 = n^4) 次比较。 这是正确的，但忽略了邻接的定义，因为远处的建筑物永远不会影响当前建筑物是否是摩天大楼。 

蛮力之所以有效，是因为检查每座建筑物可以保证不会遗漏更高的建筑物，但当网格变大时，它会失败，因为几乎所有这些比较都是无关紧要的。 关键的观察是该定义仅提到直接相邻的单元格，包括对角线。 无论大都市有多大，每栋建筑最多有八个这样的牢房。 

这一观察结果将一个单元的工作量从 (O(n^2)) 减少到 (O(1))。 我们检查单元格周围的八个可能的方向，跳过网格外的位置，并在找到高度大于或等于其高度的邻居时立即拒绝该单元格。 如果所有现有邻居都严格小于该单元格，则该单元格是一座摩天大楼。 

不需要更先进的数据结构或预处理技术。 输入已包含 (n^2) 个单元格，并且我们仅对每个单元格执行恒定量的工作，从而给出最佳 (O(n^2)) 运行时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(n^4)) | (O(1)) 除了输入 | 太慢了 |
 | 最佳 | (O(n^2)) | (O(n^2)) | 已接受 |

 ## 算法演练

 1. 将网格读取为 (n) 个字符串。 将每一行保留为字符串就足够了，因为每个高度都是一位数字。 
2. 访问每个单元格 ((r,c))。 这是必要的，因为每栋建筑都必须有一个独立的`Y`或者`N`决定。 
3. 对于当前单元格，检查从 (-1) 到 (1) 的行和列偏移的所有组合，不包括偏移 ((0,0))。 这八个偏移量代表四个侧面邻居和四个对角邻居。 
4. 对于每个候选邻居，检查其坐标是否仍在网格内。 边界和角单元的有效邻居自然少于八个，因此超出范围的位置将被忽略。 
5. 如果任何有效邻居的高度大于或等于当前高度，则将当前位置标记为`N`。 平等足以取消其资格，因为当前建筑物必须严格高于每个邻居。 
6. 如果所有有效邻居的高度都较小，则将当前位置标记为`Y`。 没有邻居的单元格，例如（1 \times 1）网格中的唯一单元格，也达到这种情况并被正确地视为摩天大楼。 
7. 打印结果 (n) 行。 

不变的是，处理一个单元格后，它的输出字符是`Y`恰好当每个现有的相邻单元具有严格较小的高度时。 该算法检查每个可能的相邻位置并仅忽略不存在的位置，因此不会错过任何相关的邻居。 由于每个单元格都是独立处理的，因此将此不变量应用于所有 (n^2) 个单元格可准确生成所需的网格。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    grid = [input().strip() for _ in range(n)]

    ans = []

    for r in range(n):
        row = []

        for c in range(n):
            height = grid[r][c]
            skyscraper = True

            for dr in (-1, 0, 1):
                for dc in (-1, 0, 1):
                    if dr == 0 and dc == 0:
                        continue

                    nr = r + dr
                    nc = c + dc

                    if 0 <= nr < n and 0 <= nc < n:
                        if grid[nr][nc] >= height:
                            skyscraper = False
                            break

                if not skyscraper:
                    break

            row.append('Y' if skyscraper else 'N')

        ans.append(''.join(row))

    sys.stdout.write('\n'.join(ans))

if __name__ == "__main__":
    solve()
```网格直接存储为字符串，因此`grid[r][c]`给出特定位置的高度字符。 由于字符是数字，因此直接比较它们是有效的，因为它们的字典顺序与来自的数字顺序相同`0`通过`9`。 

两个嵌套循环结束`dr`和`dc`枚举所有八个相邻位置。 明确的`(0, 0)`检查防止当前单元与其自身进行比较。 边界条件`0 <= nr < n and 0 <= nc < n`处理所有四个边界，没有特殊情况。 

比较使用`>=`，而不是`>`。 如果相邻建筑物的高度完全相同，则当前建筑物并不严格更高，必须进行标记`N`。 

这`skyscraper`标志开头为`True`并成为`False`一旦发现不合格的邻居。 早期的`break`一旦答案已知，语句就避免检查剩余的邻居。 这不会改变渐近复杂度，但减少了典型网格上不必要的工作。 

Python 整数在这里不需要特殊的溢出处理，因为该算法不对大小可能增长的值执行算术运算。 输出逐行累加并在最后写入一次。

## 边缘情况

 对于单体建筑来说，```
1
5
```该单元格没有有效的邻居。 八向循环仅生成超出范围的位置，因此任何比较都无法拒绝该建筑物。 旗帜依然存在`True`，算法打印`Y`。 这符合数学条件，因为每个现有的邻居（其中不存在）都具有较小的高度。 

对于相等的相邻高度，```
2
55
55
```考虑左上角的单元格。 它的右侧和底部邻居的高度均为 5。条件检查`grid[nr][nc] >= height`，所以第一个相等的邻居发生变化`skyscraper`到`False`。 每个其他细胞都会发生同样的情况，产生`NN`在两行上。 仅使用`>`这将是一个相差一式的逻辑错误，因为平等还必须防止建筑物严格更高。 

对于对角邻接，```
2
19
91
```右上角的单元格高度为 9。它的对角邻居是左下角的单元格，高度也为 9。对角线相等足以使右上角的单元格`N`。 出于同样的原因，左下角的单元格被拒绝，而高度为 1 的两个单元格被拒绝，因为存在相邻的 9。 输出是`NY / YN`，确认包括所有八个方向。 

对于边界单元，例如任何较大网格的右上角，该算法会尝试所有八个偏移，但仅接受坐标满足边界检查的偏移。 它不需要为角、边缘或内部单元设置特殊的分支。 相同的代码可以处理所有这些问题，从而消除了边界错误和差一错误的常见来源。
