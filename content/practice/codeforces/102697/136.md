 ## 解决方案
 ## 问题理解

 输入描述了学生在几个独立问题集上的表现。 每行都有以下形式`a/b`， 在哪里`a`是正确回答问题的数量，`b`是该组问题的总数。 任务是组合所有组并打印学生的正确答案总数，然后使用相同的方法打印错误答案总数`correct/total`风格。 

例如，如果集合是`2/5`和`3/5`，学生回答`2 + 3 = 5`正确提问。 有`5 + 5 = 10`总共有问题，所以最终的结果是`5/10`。 等价地，错误答案的数量为`(5 - 2) + (5 - 3) = 5`。 

官方说法给出了1秒的时间限制和256MB的内存。 它没有公布数值上限`n`在可见的问题页面上，因此最安全的设计是通过具有恒定额外状态的输入进行单次传递。 随着问题集数量的增加，具有二次工作的算法将变得不合适，而所需的计算本身只需要每个输入行处理一次。 

在一些小情况下，粗心的解析或计算可能会产生不正确的结果。 使用单个集合，例如```
1
3/7
```答案是`3/7`。 仅计算错误答案数量但忘记保留正确答案数量的解决方案将会丢失信息。 

一组也可以包含零个正确答案。 为了```
1
0/6
```正确的输出是`0/6`。 将零视为缺失值或假设每个集合至少包含一个正确答案的实现可能会失败。 

所有问题也都可以正确回答。 为了```
1
6/6
```输出是`6/6`， 不是`6/0`。 输出中的分母是问题总数，而不是错误问题数，尽管措辞从概念上要求总正确数和总错误数。 实际所需的输出格式是斜杠分隔的正确计数和总问题计数。 

最后，斜杠是输入语法的一部分，而不是数学除法运算。 为了```
2
2/5
4/6
```答案是`6/11`。 解析两个整数`/`并将它们分别相加可以避免意外执行整数除法。 

## 方法

 一个故意幼稚的解决方案可以存储迄今为止看到的每个问题集，并在读取每个新集后，再次扫描整个存储的集合以重新计算两个总数。 这是正确的，因为每次重新计算都会考虑每个集合并添加其正确计数和总计数。 读完后`k`设置，但是，它执行`k`添加，所以跨越`n`设置设置检查的数量为

 [
 1 + 2 + \cdots + n = \frac{n(n+1)}2.
 ]

为了`n = 100000`， 那是`5,000,050,000`设置检查，远远超出 1 秒程序应尝试的范围。 

蛮力方法之所以有效，是因为所需的结果只是每组独立贡献的总和，但它会重复处理已合并到答案中的信息。 关键的观察是加法是结合的。 一旦知道当前总数，新读取的集合只需贡献自己的正确计数和自己的总计数。 没有理由重新审视之前的场景。 

因此我们可以维持两个运行值。 一个存储正确答案的总和，另一个存储所有问题的总和。 对于每个输入行`a/b`，我们添加`a`到第一个值和`b`到第二个。 最后，这两个累加值正是所需的输出。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 对于大 n 来说太慢 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`n`，问题集的数量。 我们确切地知道必须处理多少分数行，因此循环可以精确地消耗这些行。 
2. 初始化`correct = 0`和`total = 0`。 这些变量代表迄今为止处理的所有组的综合得分。 
3. 对于每一个`n`行，读取一个字符串，例如`8/11`。 将其拆分为`/`获取两个整数值`8`和`11`。 
4. 将第一个值添加到`correct`和第二个值`total`。 只有当前行提供新信息，因此以前处理的集合无需再次检查。 
5. 处理完所有组后，打印`correct`和`total`隔开`/`。 累计分子是正确答案的总数，累计分母是问题的总数。 

不变量是在处理输入的任何前缀之后，`correct`等于该前缀中正确答案的总数，并且`total`等于该前缀中的问题总数。 最初两个总和都为零，因此在处理任何内容之前不变式成立。 每条输入线都将自己的贡献精确地添加到两个总和中，从而保留了不变量。 最后一行之后，前缀是整个比赛，因此这两个变量正是所需的输出。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    correct = 0
    total = 0

    for _ in range(n):
        a, b = map(int, input().strip().split('/'))
        correct += a
        total += b

    print(f"{correct}/{total}")

if __name__ == "__main__":
    solve()
```第一行被读取为整数，因为它决定了后续记录的数量。 两个累加器初始化一次并在整个循环中更新，与算法演练中的不变量相匹配。 

对于每条记录，`split('/')`将正确计数与总计数分开。 正在申请`map(int, ...)`将两个部分直接转换为整数，因此不需要手动字符处理。 

该代码添加了问题总数，而不是错误答案的数量。 这与所需的输出格式匹配，该格式打印组合正确计数除以组合总计数。 如果概念上需要错误答案计数，则它已经表示为`total - correct`。 

Python 整数会自动扩展以容纳较大的值，因此即使输入总数的总和远大于 32 位整数，也不存在整数溢出问题。 

没有数组索引或范围取决于`n`，因此主循环中不存在差一问题。 对于每个问题集，循环只执行一次。

## 边缘情况

 对于单个问题集，算法只执行一次更新。 和```
1
3/7
```初始状态是`(correct, total) = (0, 0)`。 加工`3/7`将其更改为`(3, 7)`，所以输出是`3/7`。 没有特殊情况需要`n = 1`。 

对于不包含正确答案的集合，请考虑```
1
0/6
```更新内容是`correct += 0`和`total += 6`，生产`(0, 6)`。 输出是`0/6`。 这是有效的，因为零是一个合法的贡献，并且该程序从不使用真值检查，例如`if a:`这可能会意外地跳过它。 

为了打造完美的套装，```
1
6/6
```国家变成`(6, 6)`输出是`6/6`。 分母是故意从每个分数的第二个数字开始累加的。 用错误答案计数替换它会错误地产生`6/0`。 

混合情况，例如```
3
2/5
0/3
4/4
```产生状态`(2, 5)`， 然后`(2, 8)`， 然后`(6, 12)`。 最终的答案是`6/12`。 这在同一输入中执行了零贡献和完美集合，并确认每条线对这两个总和都有独立的贡献。 

输入语法本身是另一个值得仔细处理的边界。 一行例如`8/11`在将两个部分转换为整数之前，必须按文字斜杠进行拆分。 表达式`map(int, line.split('/'))`正是这样做的，避免了整数除法并独立地保存两个数量。
