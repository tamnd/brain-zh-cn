 ## 解决方案
 ## 问题理解

 任务是计算欧拉的 totient 函数 φ(n)。 对于正整数 n， φ(n) 计算从 1 到 n 的整数 k，其与 n 的最大公约数恰好为 1。由于 gcd(n, n) = n，值 n 本身仅在 n = 1 时起作用。 

例如，当 n = 15 时，有效值为 1、2、4、7、8、11、13 和 14，因此 φ(15) = 8。输入包含一个正整数 n，输出为其总值。 官方的限制特别小：n小于1000，时间限制为一秒，内存为256 MB。 

这些界限极大地改变了实际选择。 直接解决方案可以测试从 1 到 n 的每个 k 并计算 gcd(k, n)，在欧几里得算法的通常分析中给出 O(n log n) 时间。 当 n 低于 1000 时，最多需要 999 个 gcd 计算，因此即使是这种简单的方法也非常快。 我们仍然可以通过分解 n 来导出更好的渐近解，这需要 O(√n) 次试除并使用 O(1) 额外空间。 

有几个小案例可以暴露错误。 第一个是 n = 1。唯一不超过 1 的正整数是 1，并且 gcd(1, 1) = 1，因此正确的输出是 1。对于素数 p 盲目应用公式 φ(p) = p - 1 而不单独处理 1 的程序可能会产生错误的结果。 

第二种情况是质数，例如 n = 7。```
7
```正确的输出是 6，因为从 1 到 6 的每个数字都与 7 互质。仅计算真除数或仅查找合数的粗心实现可能会出错。 

重复的素因数是另一个常见的错误来源。 为了```
60
```质因数分解为 2² × 3 × 5，正确的输出为 16。将两次出现的 2 视为两个独立的排除项会错误地在 totient 公式中应用相同的因子两次。 

## 方法

 最直接的方法遵循字面定义。 对于从 1 到 n 的每个整数 k，计算 gcd(k, n)，并在 gcd 为 1 时递增答案。这是正确的，因为 φ(n) 的定义正是此类 k 的数量。 给定输入范围的最坏情况是 n = 999，因此程序执行 999 gcd 计算。 一般来说，运行时间是O(n log n)，而额外空间是O(1)。 对于这个问题来说已经足够快了。 

更有用的方法是查看 n 的质因数，而不是检查每个候选 k。 假设 n 具有不同的质因数 p₁, p2, ..., pᵣ。 当数字 k 至少能被 n 中的一个素数整除时，它并不与 n 互质。 在从 1 到 n 的 n 个整数中，n / pᵢ 恰好可以被 pᵢ 整除。 我们可以使用包含-排除来计算这些集合的并集，但同样的推理给出了紧凑的公式

 φ(n) = n × (1 - 1/p₁) × (1 - 1/p2) × ... × (1 - 1/pᵣ)。 

关键是只有不同的质因数才重要。 它们的指数不会出现在乘积中。 

例如，60 = 2² × 3 × 5。从 60 开始，因子 2 删除一半候选，得到 30。因子 3 删除剩余候选的三分之一，得到 20。因子 5 删除五分之一，得到 16。因此 φ(60) = 16。 

因此，我们只需要找出 n 的不同质因数。 试除到 √n 就足够了。 每当找到除数 p 时，我们都会应用一次 totient 更新，然后将 p 完全除掉。 完全删除它可以保证不会再次处理相同的素数。 

暴力法更简单并且在这些约束下被接受，而因式分解方法是更好的通用技术，因为它的复杂性取决于 √n 而不是 n。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n log n) | O(n log n) | O(1) | O(1) | 已接受 |
 | 质因数分解 | O(√n) | O(√n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取n并将答案初始化为n。 我们从 n 开始，因为 totient 公式可以被视为重复删除可被每个不同质因数整除的数字的分数。 
2. 将试除数 p 设置为 2，并在 p² ≤ n 时测试可能的除数。 一旦 p² 大于剩余的 n，就不可能有另一个因子小于 p，因此任何大于 1 的剩余值本身必定是质数。 
3. 如果 p 除以 n，则使用以下公式更新答案`answer -= answer // p`。 这适用于该因素`(1 - 1/p)`仅使用整数运算，避免浮点计算。 
4. 重复将 n 除以 p，直到 p 不能整除它。 我们这样做是因为该公式只需要每个不同的质因数一次。 例如，如果因子为 2³，则 2 的更新必须发生一次，而不是三次。 
5. 移至下一个可能的除数并继续，直到 p² > n。 
6、循环结束后，如果n大于1，则剩余的n为未处理的素因数。 对此 Prime 应用最后一次客户端更新。 
7. 打印结果答案。 

不变量是在每个处理素因子 p 之后，`answer`等于从 1 到原始输入的整数数量，这些整数在迄今为止处理的每个质因数所施加的整除性限制中幸存下来。 从 n 中删除 p 的所有副本不会改变哪些整数可被 p 整除，因此每个素数恰好贡献一次乘法约简。 当分解完成后，每个可以使 gcd(k,original_n) 大于 1 的素数都已被处理，因此剩下的就是相对素数的整数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    original = n
    ans = n
    p = 2

    while p * p <= n:
        if n % p == 0:
            ans -= ans // p

            while n % p == 0:
                n //= p

        p += 1

    if n > 1:
        ans -= ans // n

    print(ans)

if __name__ == "__main__":
    solve()
```变量`ans`从原始 n 开始，并为每个不同的质因数更新一次。 表达式`ans -= ans // p`是乘以的整数形式`(p - 1) / p`，因此不涉及浮点运算。 

内部`while`循环删除当前素因数的每次出现。 这是一个微妙但必要的细节。 对于n=60，求出2后，n的值为15。因子2已经被考虑在内，所以不必再考虑。 

循环条件`p * p <= n`也是故意的。 一旦当前除数超过剩余 n 的平方根，则最多只能有一个剩余因子，并且该因子必须是素数。 检查`n > 1`在循环精确处理这种情况之后。 

Python 整数不存在 C++ 等语言可能遇到的固定宽度溢出问题，尽管这里无论如何都不需要大的中间值。

对于样本 2，输入为 60。其分解为 2² × 3 × 5。

 ## 边缘情况

 最小可能的输入是 n = 1。```
1
```算法初始化`ans = 1`。 由于没有要处理的除数，并且剩余的 n 不大于 1，因此答案仍为 1。这与定义一致，因为 gcd(1, 1) = 1。 

一个主要输入，例如```
7
```永远不会进入要素处理分支。 在测试除数直到 7 的平方根后，剩余的 n 仍然是 7。最终更新计算`7 - 7 // 7 = 6`，这是素数的正确目标。 

可以看到重复的素因数```
60
```第一个发现的因子是 2。答案从 60 变为 30，内部循环删除了 2 的两个副本，将工作 n 从 60 更改为 15。素数 2 不再被应用。 然后剩下的因子 3 和 5 将答案减少到 20，最后减少到 16。 

最大输入为```
999
```因式为 3³ × 37。算法找到 3，应用一次全数约简，并删除 3 的所有三个副本。试循环后剩余值 37 大于 1，因此将其识别为素因数并处理一次。 结果是648。 

一个主要的力量，例如```
729
```对于捕获每个指数应用一次 totient 更新的错误特别有用。 由于 729 = 3⁶，因子 3 只能影响公式一次。 正确的计算结果是算法生成的 729 × (1 - 1/3) = 486。
