 ## 解决方案
 ## 问题理解

 我们一次接收一个整数序列。 每个整数到达后，必须将其插入到一个按非递减顺序保存的列表中。 所需的输出不仅仅是最终的排序序列。 在第一个值之后，我们打印单元素排序列表。 在第二个值之后，我们打印包含这两个值的排序列表，依此类推，直到插入每个值。 

例如，如果传入序列是`3, 4, 2, 8, 7`，维护的列表是`[3]`,`[3, 4]`,`[2, 3, 4]`,`[2, 3, 4, 8]`， 和`[2, 3, 4, 7, 8]`。 

该声明没有给出明确的上限`n`。 时间限制为 1 秒，内存限制为 256 MB。 更重要的是，输出本身包含

 1+2+⋯+n=2n(n+1)​

 整数，因此仅仅写出所需的答案就已经花费了二次方的时间`n`。 这排除了具有附加对数或线性因子的算法，如果`n`很大。 我们希望维护工作不比不可避免的输出尺寸更差。 

第一个边缘情况是重复值。 用于输入```
3555
```正确的输出是```
55 55 5 5
```仅搜索严格较小的值的实现可能会错误地处理相等的元素，尽管如果相等的值彼此相邻插入，最终顺序仍然有效。 

另一个边缘情况是插入新的最小值。 为了```
3421
```输出是```
42 41 2 4
```当插入位置索引为零时，仅处理第一个元素之后某处的插入的粗心实现可能会失败。 

对称情况是插入新的最大值。 为了```
3135
```输出是```
11 31 3 5
```插入位置位于末尾，因此假设在插入点之后始终有一个元素要移动的实现可以越过数组边界。 

## 方法

 直接的解决方案是显式维护排序列表。 对于每个传入的数字，从头开始扫描现有列表，直到找到第一个大于新数字的元素，将数字插入其中，然后打印整个列表。 这是正确的，因为插入位置之前的所有内容最多都是新值，而从该位置开始的所有内容都大于或等于新值。 

在最坏的情况下，插入`k`th 值可能需要移位`k-1`现有的元素。 在所有插入中，这给出了

 0+1+2+⋯+(n−1)= 2 n(n−1) ​

 元素运动。 打印答案还需要恰好 n(n+1)/2 个整数输出。 因此，总工作量为 O(n 2 )，这与所请求的输出的不可避免的大小相匹配。 

使解决方案变得简单的观察结果是输出本身是二次的。 无需搜索能够在 O(logn) 时间内插入的奇异数据结构，因为即使是完美的插入结构仍然需要打印 O(n 2 ) 值。 Python 列表与二分搜索相结合提供了一个干净的实现：二分搜索在 O(logn) 中找到插入位置，并且列表插入在 O(n) 中移动元素。 后者占主导地位，总时间为 O(n 2 )。 

暴力版本可以使用线性搜索插入位置，而最佳实现使用二分搜索。 两者具有相同的渐近复杂度，因为移动 Python 列表已经是线性的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 线性搜索+插入| O(n²) | O(n) | 已接受 |
 | 二分查找+插入 | O(n²) | O(n) | 已接受 |

 二分搜索版本更可取，因为找到插入位置的成本仅为 O(logn)，尽管总复杂度仍为 O(n 2 )。 

## 算法演练

 1. 阅读`n`并初始化一个名为的空列表`arr`。 该列表准确地表示了迄今为止已到达的排序值。 
2.读取每个传入的值`x`为了。 之前的内容`arr`已经排序了，所以我们只需要找到哪里`x`属于.
 3.使用二分查找查找第一个索引`pos`这样`arr[pos] >= x`。 这是标准的下限位置。 如果每个现有值都小于`x`，位置变为`len(arr)`， 意义`x`属于最后。 
4. 插入`x`在`pos`。 Python 将现有后缀向右移动，留下`arr`已排序。 
5. 打印所有元素`arr`。 此时此刻`arr`恰好包含第一个`k`输入值按排序顺序排列，因此这正是所需的输出`k`th 行。 
6. 重复直到所有`n`值已被处理。 

### 为什么它有效

 不变量是在处理新值之前，`arr`准确包含到目前为止看到的值，并按非降序排序。 二分查找找到可以放置新值而不违反该顺序的第一个位置。 该位置之前的每个元素都小于新值，并且从该位置开始的每个元素都大于或等于新值。 插入后，不变量仍然为真。 因此，每个打印的列表正是问题所需的排序前缀。 

## Python 解决方案```python
Pythonimport sysfrom bisect import bisect_left
input = sys.stdin.readline

def solve():    n = int(input())    arr = []    output = []
    for _ in range(n):        x = int(input())
        pos = bisect_left(arr, x)        arr.insert(pos, x)
        output.append(" ".join(map(str, arr)))
    sys.stdout.write("\n".join(output))

if __name__ == "__main__":    solve()
```

`bisect_left`实现步骤 3 中使用的下限。使用至少包含一个值的第一个位置`x`意味着将相等的值插入到现有的相等值之前，这是完全有效的，因为所需的排序是非递减的。`arr.insert(pos, x)`是执行实际动态插入的部分。 如果`pos`为零，所有现有元素都向右移动。 如果`pos == len(arr)`，Python 自然地附加该值。 这两个边界覆盖了最小和最大可能的插入位置。 

输出作为字符串累积并在最后写入一次。 反复呼唤`print`每一行在逻辑上仍然是正确的，但是构建完整的输出并做出最终的`sys.stdout.write`避免不必要的 I/O 调用。 输出本身的大小是二次方的，因此字符串在以下情况下必然会消耗大量内存：`n`很大。 流式实现可以减少额外的内存，但上面的版本使代码保持简单。 

Python 整数具有任意精度，因此不存在整数溢出问题。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|

问题陈述没有提供最大值`n`，因此无需进行诚实的固定上限计算。 该解对于所需的输出大小是渐近最优的。

## 边缘情况

 对于重复值，请考虑：```
3555
```最初`arr`是空的，所以第一个`5`被插入到零位置。 对于第二个`5`,`bisect_left([5], 5)`返回零，列表变为`[5, 5]`。 第三次插入的行为相同，产生`[5, 5, 5]`。 因此输出是`5`， 然后`5 5`， 然后`5 5 5`。 相等的值不需要特殊情况，因为下界自然可以处理它们。 

对于在开头插入，请考虑：```
3421
```读完后`4`，列表是`[4]`。 阅读`2`给出位置零，因为`2`小于`4`，生产`[2, 4]`。 阅读`1`再次给出位置零，产生`[1, 2, 4]`。 该算法从不访问负索引或假设插入点有前趋。 

对于在末尾插入，请考虑：```
3135
```后`[1, 3]`，寻找`5`回报`pos = 2`，等于当前列表长度。`arr.insert(2, 5)`因此附加该值并产生`[1, 3, 5]`。 该实现不需要单独的追加分支，因为 Python 的插入操作可以正确处理此边界。 

最后，第一个元素值得单独关注，因为没有现有的排序前缀可供搜索。 和```
142
```列表为空，`bisect_left([], 42)`返回零，结果很简单`42`。 这从第一次迭代中建立了不变量，之后的每次迭代都对已经排序的列表进行操作。
