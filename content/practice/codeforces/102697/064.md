 ## 解决方案
 ## 问题理解

 任务是计算一辆车行程的燃油费用。 输入给出了三个浮点值：汽车的燃油效率（以英里/加仑为单位）、行驶距离（以英里为单位）以及一加仑汽油的价格。 

如果汽车行驶`distance`里程并获得`mpg`每加仑英里，需要的汽油量是

 [
 \frac{\text{距离}}{\text{mpg}}
 ]

 加仑。 将该数量乘以一加仑的价格即可得出总行程成本：

 [
 \text{成本} =
 \frac{\text{距离}}{\text{mpg}}
 \次
 \text{每加仑价格}。 
]

 所需的输出是作为浮点值得到的美元金额。 官方声明指定了一个测试用例，其中恰好包含三个浮点值。 

已发布的声明中的三个浮点值没有明确的数值范围。 这使得基于输入大小的渐近算法变得不必要。 整个问题包括读取三个数字并执行两个算术运算，因此无论它们的值如何，运行时间都是恒定的。 

一种常见的边缘情况是零距离旅行。 例如，使用输入`20 0 5`，汽车消耗零加仑，所以正确的输出是`0.0`。 如果不小心将距离乘以燃油效率而不是除以燃油效率，则会产生错误的结果。 

另一个有用的边界情况是燃料价格为零。 例如，`20 100 0`需要五加仑，但每一加仑都是免费的，所以答案是`0.0`。 该公式自然地处理了这个问题。 

第三种情况是燃料效率不是整数时。 用于输入`7.5 30 4`,汽车需要`30 / 7.5 = 4`加仑，给出答案`16.0`。 将值读取为整数的实现在到达计算之前就会失败。 

发布的样本是`10 100 3.5`。 车需要`100 / 10 = 10`加仑和十加仑`⟦PROTECT_4⟧35.00`，所以输出是`35.0`。 

## 方法

 字面上的蛮力方法会模拟每次一个单位距离的行程并累积相应的燃料成本。 如果距离是整数`D`，这需要`D`迭代，每次代表又行驶了一英里。 因此，其最坏情况的操作计数将与`D`， 或者`O(D)`。 对于这个问题来说，这已经是不必要的了，并且实际距离是浮点值，因此甚至没有可以迭代的自然离散单位。 

蛮力想法之所以有效，只是因为总成本可以被视为旅行中每个小部分的成本之和。 关键的观察结果是，每一英里的燃油成本都是相同的，因此在旅途中没有任何状态发生变化。 我们可以直接计算消耗的加仑数，而不是模拟消耗。 将总距离除以每加仑英里数即可得出一次操作中的确切燃油需求，然后乘以加仑价格即可得出答案。 

因此整个问题可以简化为表达式

 [
 \frac{距离\乘以价格}{mpg}。 
]

 不需要数组、循环、动态编程、图形算法或数值搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(D) 对于整数距离 D | O(1) | O(1) | 不必要也不适合任意浮点距离|
 | 直接配方| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将三个浮点值读取为`mpg`,`distance`， 和`price`。 

需要浮点输入，因为燃油效率和汽油价格都可能包含小数值。 
2. 将距离除以燃油效率即可计算消耗的加仑数。 

一辆会旅行的车`mpg`每加仑英里需要`distance / mpg`加仑行驶所需的距离。 
3. 将加仑数乘以每加仑的价格。 

这会将燃油量转换为行程的总货币成本。 
4. 打印生成的浮点值。 

Python 的标准浮点输出足以解决此问题，并生成示例输出：`35.0`。 

### 为什么它有效

 燃油效率表明每加仑汽车都能精确行驶`mpg`英里。 扭转这种关系，行驶一英里会消耗`1 / mpg`加仑，所以旅行`distance`里程消耗`distance / mpg`加仑。 由于每加仑的成本相同`price`，将消耗的加仑数乘以该价格就可以得出此次旅行支付的总金额。 该算法精确地执行了这两个转换，因此其结果就是所需的 Gas 成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    mpg, distance, price = map(float, input().split())

    gallons = distance / mpg
    cost = gallons * price

    print(cost)

if __name__ == "__main__":
    solve()
```一线进口`sys`， 和`input`被分配给`sys.stdin.readline`根据快速标准输入的要求。 尽管这里的输入大小很小，但这是常见的竞争性编程设置。 

三个值的解析为`float`因为该语句明确允许浮点值。 变量`gallons`代表消耗的燃料的物理量，这使得计算更容易阅读并反映了数学推导。 

划分必须在应用价格之前进行。`distance / mpg`单位为加仑，乘以每加仑美元得到美元。 按此顺序编写计算还可以避免将燃油效率与燃油消耗混淆。 

蟒蛇的`float`使用双精度浮点运算。 不存在整数溢出问题，因为计算从不使用整数大小的累加器，并且只处理三个值。

 ## 边缘情况

 对于零距离，准确的输入是`1 0 10`。 该算法计算`0 / 1 = 0`加仑，然后`0 * 10 = 0`, 生产`0.0`。 不需要特殊条件，因为公式已经正确捕获了物理情况。 

对于零燃油价格，输入`20 100 0`需要`100 / 20 = 5`加仑。 最终的乘法是`5 * 0 = 0`，所以输出是`0.0`。 这证实了该算法正确地将燃料消耗与燃料价格分开。 

对于燃油效率分数，请考虑`7.5 30 4`。 该部门给出`30 / 7.5 = 4`加仑，最后的乘法给出`4 * 4 = 16`。 读取输入`float`是什么允许`7.5`才能正确表示。 

对于官方样品`10 100 3.5`，计算为`100 / 10 = 10`加仑 随后`10 * 3.5 = 35`。 打印的结果是`35.0`，与官方输出匹配。 

主要的实施陷阱是逆转第一个操作。 每加仑英里数告诉我们一加仑可以行驶多少英里，因此消耗的燃料是距离除以每加仑英里数。 将距离乘以每加仑英里会得到错误的单位，并会产生错误的答案。
