 ## 解决方案
 ## 问题理解

 当忽略空格时，我们会得到一个最多包含七个字符的目标字符串，后面跟着一个单词字典。 我们需要打印字典单词的每个不同序列，其组合字母恰好是目标字母，忽略单词之间的空格。 单词的顺序很重要，所以`arm code`和`code arm`都是不同的答案。 答案必须按字母顺序打印。 重复的字典条目不得导致相同的短语被打印两次。 

例如，与目标`coderam`，字典包含`arm`,`code`,`coderam`,`dore`， 和`mac`。 单个词`coderam`是有效的，同时`arm code`和`code arm`也是有效的，因为这三个都包含完全相同的七个字母。 一个词，比如`codes`无法参加，因为它需要`s`目标中不存在。 

目标长度是中心约束。 最多七个字符意味着只有少量可能的剩余字母状态。 如果所有七个字符都不同，则每个状态对应于选择这七个字符的某个子集，最多给出 (2^7=128) 个状态。 重复的字符只会减少这个数字。 官方时间限制为 15 秒，内存限制为 256 MB，因此预期的解决方案能够处理字典并枚举实际答案，但应避免探索字典单词的任意组合。 

Codeforces 显示的语句中的字典大小没有有用的数字上限，因此在打印答案的不可避免的成本之前，算法应该在字典大小上接近线性或接近线性。 七个字符的限制正是为我们提供了这样的机会。 

第一个边缘情况是重复的字典条目。 考虑：```
a
2
a
a
```正确的输出是：```
a
```两个字典行代表同一个单词，因此将字典条目视为单独的选择会错误地打印`a`两次。 

第二个边缘情况是包含目标中从未出现过的字母的字典单词。 考虑：```
ab
2
a
ac
```正确的输出是：```
a
```这个词`ac`不能是字谜词的一部分，因为目标不包含`c`。 仅比较字长的粗心实现可以接受它。 

第三种边缘情况是重复的字母。 考虑：```
aa
2
a
aa
```正确的输出是：```
a a
aa
```这个词`a`可以使用两次，因为目标包含两个副本`a`。 假设每个字典单词最多可以使用一次的解决方案将会错过`a a`。 

第四种边缘情况涉及当一个答案是另一个答案的前缀时按字母顺序排列。 考虑：```
ab
2
a
ab
```正确的输出是：```
a b
ab
```比较是在完整的输出字符串之间进行的。 自从`a b`有`a`后跟一个空格和`ab`有`b`，正常的词典比较位置`a b`前`ab`。 DFS 必须根据实际的字符串而不是长度来生成答案。 

## 方法

 最直接的蛮力想法是尝试字典单词的每个有序序列。 由于目标最多包含七个字符，因此有效答案最多可以包含七个单词，因为每个字典单词至少包含一个字符。 对于 (n) 个字典单词，长度为 1 到 7 的序列的数量为

 [
 n+n^2+n^3+\cdots+n^7。 
]

 对于大 (n)，最后一项占主导地位，因此这是 (O(n^7)) 候选序列。 如果我们还检查每个所选单词中的字母以检查它们的组合多重集是否等于目标，则每个候选者的工作是另一个以七个目标字符为界的常数。 蛮力是正确的，因为考虑了每个可能的有序序列，但 (n^7) 增长得太快。 

例如，即使 (n=100) 仅给出大约 (10^{14}) 个七个单词的序列。 无法枚举 15 秒限制内的内容。 

暴力方法失败了，因为它将字典大小视为组合复杂性的来源。 目标长度告诉我们几乎所有字典单词都是无关的。 仅当单词包含的每个字符都可以从目标中取出时，单词才可用，并且在选择单词后，只有其余字母才重要。 

用多组字母表示每个单词。 如果目标是`coderam`我们选择`arm`，下一个决定所需的唯一信息是剩余的字母是`cdeor`。 我们不关心这些字母最初占据哪个位置。 留下相同剩余多重集的两条不同路径正在解决完全相同的子问题。 

最多可以有 128 个这样的状态。 我们可以存储可用于每个状态的字典单词，然后对剩余字母状态执行 DFS。 每当剩余状态为空时，当前序列就是一个完整的答案。 

订购要求自然适合这种方法。 如果所有可用的字典单词都按字母顺序存储，并且 DFS 按该顺序尝试它们，则以较小的第一个单词开始的每个完成都会在每个以较大的第一个单词开始的完成之前生成。 同样的论点递归地适用于后面的单词。 因此，DFS 本​​身会按字典顺序生成完整的短语，因此我们不需要事后收集和排序潜在的巨大答案集。 

在搜索之前删除重复的字典条目。 具有相同字母多重集的不同单词会被保留，因为它们产生真正不同的短语。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(n^7)) 候选序列 | (O(7)) 递归深度 | 太慢了 |
 | 基于状态的 DFS | (O(n\log n + 128n + A)) | (O(128n + 7)) | 已接受 |

 这里 (A) 代表输出量以及生成它所需的递归工作。 由于程序必须打印每个有效答案，因此解决方案无法渐近地避免与输出大小成比例的工作。 

## 算法演练

 1. 读取目标字符串并去除其中的空格。 由于空格不会为字谜词贡献字母，因此目标仅由其实际字符表示。 
2. 收集目标中出现的不同字符并为每个字符分配一个索引。 例如，对于`coderam`，相关字符是`c`,`o`,`d`,`e`,`r`,`a`， 和`m`。 
3. 用计数向量表示目标。 每个组件存储一个相关角色剩余的数量。 字典中的单词具有相同的表示形式。 如果它包含目标之外的字符，请立即丢弃它，因为它永远不会出现在有效答案中。 超过七个字符的单词也自动无关。 
4. 删除重复的字典单词并按字母顺序对剩余的相关单词进行排序。 将原始单词与其计数向量一起保留，可以让我们打印准确的拼写，同时使用紧凑向量进行所有字谜检查。 
5. 将 DFS 状态定义为尚未使用的字母的计数向量。 初始状态是完整的目标向量。 空向量意味着每个计数为零，代表一个完整的有效短语。 
6. 对于给定的剩余状态，按字母顺序考虑每个相关的字典单词。 当一个单词的每个字符数最多等于相应的剩余字符数时，就可以准确地选择一个单词。 
7. 从剩余状态中减去所选单词的计数并递归地求解较小的状态。 稍后可以再次选择相同的词典单词，因为词典成员资格并不意味着条目在一次使用后被消耗。 剩余字母数决定是否可以容纳另一个副本。 
8. 在给出答案之前，使用记忆的可行性 DFS 来确定状态是否可以达到零。 在输出生成期间，仅遵循导致可解状态的转换。 这会删除那些以永远无法完成目标的方式消耗字母的死分支。 
9. 当剩余状态为零时，打印当前序列。 由于在每个递归级别都按字母顺序考虑选择，因此生成的短语已经按字母顺序排列。 

### 为什么它有效

 不变量是每个递归状态准确地表示目标中尚未分配给当前前缀中的单词的字母。 仅当所选词典单词的字母计数适合该状态时才允许转换，因此新状态恰好是旧状态减去该单词。 当状态达到零时，所选单词总共包含精确的目标字母，使该短语成为有效的字谜词。 

相反，采取任何有效的答案并从左到右考虑它的单词。 每个单词都属于字典，并且仅使用前面单词之后仍然可用的字母，因此 DFS 在每一步都有相应的有效转换。 它最终将达到零状态并产生答案。 删除重复的字典条目可以保证相同的短语不会生成两次。 按字母顺序遍历保证了所需的输出顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    target = input().rstrip("\n").replace(" ", "")
    n = int(input())

    if not target:
        for _ in range(n):
            input()
        return

    chars = sorted(set(target))
    index = {ch: i for i, ch in enumerate(chars)}
    k = len(chars)

    target_count = [0] * k
    for ch in target:
        target_count[index[ch]] += 1

    words = set()

    for _ in range(n):
        word = input().rstrip("\n")

        if len(word) > len(target):
            continue

        count = [0] * k
        ok = True

        for ch in word:
            pos = index.get(ch)
            if pos is None:
                ok = False
                break
            count[pos] += 1
            if count[pos] > target_count[pos]:
                ok = False
                break

        if ok:
            words.add(word)

    words = sorted(words)

    if not words:
        return

    word_data = []
    for word in words:
        count = [0] * k
        for ch in word:
            count[index[ch]] += 1
        word_data.append((word, tuple(count)))

    initial = tuple(target_count)

    candidate_cache = {}

    def candidates(rem):
        if rem in candidate_cache:
            return candidate_cache[rem]

        result = []
        for word, cnt in word_data:
            ok = True
            for i in range(k):
                if cnt[i] > rem[i]:
                    ok = False
                    break

            if ok:
                result.append((word, cnt))

        candidate_cache[rem] = result
        return result

    feasible = {}

    def can_solve(rem):
        if not any(rem):
            return True

        if rem in feasible:
            return feasible[rem]

        for _, cnt in candidates(rem):
            nxt = tuple(rem[i] - cnt[i] for i in range(k))
            if can_solve(nxt):
                feasible[rem] = True
                return True

        feasible[rem] = False
        return False

    if not can_solve(initial):
        return

    answer = []
    current = []

    def generate(rem):
        if not any(rem):
            answer.append(" ".join(current))
            return

        for word, cnt in candidates(rem):
            nxt = tuple(rem[i] - cnt[i] for i in range(k))

            if can_solve(nxt):
                current.append(word)
                generate(nxt)
                current.pop()

    generate(initial)

    sys.stdout.write("\n".join(answer))

if __name__ == "__main__":
    solve()
```首先通过删除空格来标准化目标。 然后在阅读时对字典进行过滤。 这`index`映射使得一旦单词包含目标中不存在的字符就可以拒绝该单词。 

这`words`set 删除重复的字典条目。 我们随后进行排序，而不是在输入期间维护排序结构，这使字典处理变得简单。 

每个保留字都会转换为计数元组。 元组长度最多为 7，因为它仅包含目标中出现的字符。 元组是不可变且可散列的，因此它可以用作存储的字典键。 

这`candidates`函数缓存适合特定剩余状态的所有字典单词。 最多有 128 个不同的状态，因此即使它扫描字典，每个状态也只能扫描一次。 

这`can_solve`函数回答了一个较小的决策问题：剩余的多重集是否可以完成？ 它的记忆非常有用，因为可以通过许多不同的前缀达到相同的剩余状态。 

这`generate`函数只负责产生答案。 它减去单词的计数向量，检查结果状态是否可行，然后递归地继续。 这`current`列表代表确切的短语前缀。 

整数不可能溢出，因为每次计数最多为 7。 递归深度也最多为七，因为每个选定的单词至少消耗一个目标字符。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(n\log n + 128n + A)) | 对相关字典进行排序成本（O(n\log n)），最多 128 个状态扫描字典，(A) 表示生成的输出及其递归工作 |
 | 空间| (O(128n + A_{\text{缓冲区}} + 7)) | 在最坏的情况下，缓存的候选列表使用 (O(128n)) 空间，而递归深度最多为 7 |

 决定性因素是七字目标。 即使有 7 个不同的字符，也只有 128 个可能的剩余字母多重集。 字典可能很大，但它永远不会通过 (n^7) 种组合来探索。 剩下的工作主要是字典扫描和打印答案本身，这是不可避免的。 

官方限制为 15 秒和 256 MB。 该算法使用较小的目标长度来保持状态空间很小，同时避免对特定字母表的任何假设。

 大型测试故意使用 100000 个不相关的字典条目，因为问题陈述没有公布 (n) 的最大值。 它练习了对于大型字典来说很重要的行为，而不会产生巨大的预期输出。 

## 边缘情况

 对于重复的字典条目，请考虑：```
a
2
a
a
```目标状态是`(1)`。 字典集只包含一个`a`，因此 DFS 达到空状态一次并打印`a`一次。 如果没有重复数据删除，相同的递归路径将由两个相同的字典条目表示，并且输出将是重复的。 

对于不可用的字符，请考虑：```
ab
2
a
ac
```目标仅包含`a`和`b`。 读书时`ac`, 字符`c`目标中没有索引，因此该单词在进入 DFS 之前被丢弃。 唯一可能的输出是`a`如果目标没有完全覆盖，那么在这个精确的输入中实际上没有完整的字谜，并且正确的输出为空。 正确实现不会产生任何输出。 

对于重复的字母和单词重用，请考虑：```
aa
2
a
aa
```初始计数是两个副本`a`。 选择`a`留下一份，所以选择`a`再次有效并达到零。 选择`aa`立即消耗两个副本。 输出是：```
a a
aa
```搜索没有标记`a`作为全球使用的。 只有剩余的计数才能确定是否适合另一个出现的情况。 

对于按字母顺序排序，请考虑：```
ab
3
a
b
ab
```字典排序为`a`,`ab`,`b`。 开始于`a`产生`a b`，出现在之前`ab`。 这`ab`分支然后产生`ab`，随后是`b a`分支。 输出是：```
a b
ab
b a
```排序来自于 DFS 之前对实际词典单词的排序，而不是根据单词长度或字母签名进行排序。 

最后，考虑一个包含比目标长的单词的字典：```
abc
3
abcd
ab
c
```

`abcd`被立即拒绝，因为其长度大于可用目标字符的数量。 剩下的单词可以组合成`ab c`，所以输出是：```
ab c
```这种早期过滤对于正确性来说并不是必需的，但它可以防止明显不可能的单词进入状态搜索，并且直接遵循每个目标字符必须仅使用一次的事实。
