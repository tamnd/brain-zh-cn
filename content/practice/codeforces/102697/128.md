 ## 解决方案
 ## 问题理解

 我们给出一个包含至少两个正分数的表达式，其中`+`每对之间。 每个分数都有一个整数分子和分母。 任务是准确评估整个总和，然后以最低的形式打印结果。 如果减少的分母是`1`，答案被打印为整数而不是`x/1`。 

主要困难不是分数加法的数学。 它控制中间整数的大小。 该问题的设计目的是，即使最终答案保证适合 Java，粗心的实现也可能会产生巨大的共同点。`int`当计算被有效地组织时。 官方限制仅为一秒，因此实现应该为每个输入分数执行少量整数算术和 GCD 运算，而不是构造不必要的大公分母。 

没有单独的测试用例计数。 整个表达式出现在一个输入行上，并且分数的数量可能很大。 问题设置者明确使用具有六个分数的样本作为性能检查。 将每个分母重复乘以一个巨大乘积的解决方案可以比实际答案更快地增长其中间值。 减少运行结果的解决方案可以避免不必要的增长。 

常见的边缘情况是答案变成整数。 例如，```
2/3 + 7/3
```有价值`3`，所以正确的输出是```
3
```粗心的实现可能会打印`3/1`，它表示相同的数学值，但不遵循所需的输出格式。 

另一个极端情况是分母共享因子。 例如，```
1/6 + 1/4
```有液晶模组`12`，所以结果是`5/12`。 分母相乘得出`24`，它仍然会产生数学上正确的结果，但它会产生不必要的大中间分母。 在许多分数上重复这个错误可能会使中间整数远远大于所需的值。 

当输入分数本身没有减少时，就会出现第三种边缘情况。 例如，```
2/4 + 1/4
```简直就是`3/4`。 即使第一个分数没有减少，加法公式仍然有效，前提是运行结果在加法后减少了。 假设每个输入分数已经是最低项的实现可以在以后的每个操作中默默地携带不必要的因素。 

## 方法

 最直接的暴力方法是为整个表达式选择一个公分母。 如果分数是`a1/b1`,`a2/b2`， 通过`ak/bk`，我们可以取`B = b1*b2*...*bk`，将每个分子乘以适当的缺失分母因子，添加所得分子，最后减少一次。 这在数学上是正确的，因为每个原始分数都转换为具有分母的等价分数`B`。 

问题是尺寸`B`。 即使最终的简化答案很小，所有分母的乘积也可能是巨大的。 如果输入包含`k`大小约为的成对互质分母`M`，共同点是关于`M^k`。 该算法仅执行 O(k) 分数项，但其算术是在具有 θ(k log M) 位的整数上执行的。 在 Java 等固定宽度语言中，乘法可能会在最终答案返回到适合某个值的值之前溢出。`int`。 该问题明确警告即使最终的输入和输出值符合 Java 的要求，高效的计算也是必要的。`int`范围。 

更好的方法是一次添加一个分数，并在每次添加后减少运行分数。 假设当前结果是`p/q`下一个分数是`a/b`。 而不是使用`q*b`立即，首先计算`g = gcd(q,b)`。 分母的最小公倍数是`(q/g)*b`。 新的分子可以根据该分母来构造。 然后，将分子和分母除以它们的 GCD。 

使这项工作有效的观察结果是，最终答案只需要分母实际所需的公因数。 当两个分母共享一个因子时，它们的 LCM 会保留该因子的一个副本，而不是将两个副本相乘。 每次添加后进行归约可以防止随后取消的因子被带入表达式的其余部分。 

蛮力法之所以有效，是因为一个公分母准确地代表了每个分数，但它失败了，因为该分母可能包含许多最终被取消的因子。 每个部分和本身都可以由一个约简分数表示这一观察结果让我们立即丢弃那些不必要的因素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(k) 算术运算，但可能具有指数大小的整数 | O(1) 超出输入 | 太慢或容易溢出 |
 | 最佳 | O(k log V) GCD/算术工作，其中`V`由相关整数大小限制 | O(1) 超出输入 | 已接受 |

 这里`k`是分数的个数，`V`表示减少的中间分子和分母的大小。 GCD 运算的参数是对数的。 

## 算法演练

 1. 阅读完整的表达式并提取每个分数。 由于每个操作都是加法，因此包含的标记`+`可以忽略，留下以下形式的字符串`numerator/denominator`。 
2. 从第一个分数开始运行结果，将其存储为`p/q`。 立即减少。 保持运行分数减少的不变性可以防止不必要的因素积累。 
3. 对于每个剩余分数`a/b`, 计算`g = gcd(q, b)`。 价值`g`正是两个分母中不需要在 LCM 中重复的部分。 
4. 设置`q1 = q/g`和`b1 = b/g`。 新的分母是`q1*b`，即`lcm(q,b)`。 
5. 将两个分数转换为该公分母。 第一个贡献`p*b1`，而新的分数贡献`a*q1`，所以新的分子是`p*b1 + a*q1`。 
6. 通过计算减少结果分数`h = gcd(numerator, denominator)`并将两个值除以`h`。 这将运行结果返回到分子和分母互质的不变量。 
7. 处理完所有分数后，如果分母是，则直接打印分子`1`。 否则打印`numerator/denominator`。 

### 为什么它有效

 每次迭代后，运行对`p/q`准确地表示迄今为止处理的所有分数的总和，并且`gcd(p,q) = 1`。 对于下一个分数`a/b`,`q/g * b`， 在哪里`g = gcd(q,b)`，是两个分母的最小公倍数。 因此，构造的分子正是该公分母之和的分子。 将两个部分除以它们的 GCD 只会改变表示形式，而不会改变值，因此不变量仍然成立。 在最后的分数之后，运行值正是所请求的总和并且已经是最简单的形式。 

## Python 解决方案```python
import sys
from math import gcd

input = sys.stdin.readline

def solve():
    expr = input().strip()

    tokens = expr.replace("+", " ").split()

    first_num, first_den = map(int, tokens[0].split("/"))
    g = gcd(first_num, first_den)
    p = first_num // g
    q = first_den // g

    for token in tokens[1:]:
        a, b = map(int, token.split("/"))

        g = gcd(q, b)

        q1 = q // g
        b1 = b // g

        p = p * b1 + a * q1
        q = q1 * b

        g = gcd(p, q)
        p //= g
        q //= g

    if q == 1:
        print(p)
    else:
        print(f"{p}/{q}")

if __name__ == "__main__":
    solve()
```第一个解析操作将表达式转换为独立的分数标记。 更换`+`通过空格就足够了，因为表达式仅包含加法，因此不需要处理运算符优先级或括号。 

第一个分数在循环之前被减少。 这对于正确性来说并不是严格必要的，但它在处理第二个分数之前建立了相同的不变量，并从一开始就使中间值保持较小。 

在循环内部，`gcd(q, b)`在分母相乘之前使用。 表达式`q1 * b`因此是 LCM 而不是原材料。 分子使用匹配因子`b1`和`q1`，因此两个分数都精确地用该 LCM 表示。 

第二个 GCD 是必要的，因为和的分子可以与分母引入额外的公因数。 例如，添加`1/2`和`1/2`产生`4/4`在减少之前，它必须成为`1/1`。 

Python 整数不会溢出，这在这里很有用，因为问题的保证是用 Java 来表述的`int`有效实施的价值观。 该算法仍然有意控制中间增长，因为即使在 Python 中，避免大整数对于性能也很有价值。 

输出检查使用`q == 1`，而不是检查是否`p % q == 0`。 因为分数保持在最低项，所以分母为`1`正是输出格式所要求的条件。

 ## 边缘情况

 第一个边缘情况是整数结果。 为了```
2/3 + 7/3
```第一个状态是`2/3`。 第二个分母已经等于`3`，所以新的分子变成`2 + 7 = 9`, 给予`9/3`。 第二个 GCD 是`3`，将状态减少为`3/1`。 决赛`q == 1`检查打印`3`，完全符合样品的要求。 

第二个边缘情况是未减少的输入分数：```
2/4 + 1/4
```第一个分数立即从`2/4`到`1/2`。 下一个分数有分母`4`， 所以`gcd(2,4) = 2`。 液晶模组是`2/2 * 4 = 4`，分子变为`1*2 + 1*1 = 3`。 该州是`3/4`，所以输出是`3/4`。 假设输入分数已经减少的解决方案在数学上仍然能够解决该问题，但携带未减少的表示会产生不必要的因素。 

第三种边缘情况是共享分母因子：```
1/6 + 1/4
```分母有 GCD`2`，所以他们的 LCM 是`6/2 * 4 = 12`。 分子是`1*2 + 1*3 = 5`, 给予`5/12`。 直接乘以分母将使用`24`，生产`10/24`减量前。 两种表示在数学上是等效的，但 LCM 方法避免了不必要的增长。 

最后的边缘情况是在多次加法后取消为整数：```
1/2 + 1/3 + 1/6
```在前两个分数之后，状态是`5/6`。 最后的分数具有相同的分母，因此分子变为`5 + 1 = 6`, 给予`6/6`。 最终的 GCD 将其减少为`1/1`，程序打印`1`。 此案例检查每次加法后是否发生缩减，并且仅在分数完全缩减后才应用整数格式。
