 ## 解决方案
 ## 问题理解

 帕斯卡三角形从第 0 行开始仅包含`1`。 后面的每一行都是通过放置形成的`1`两端，并使每个内部值等于其正上方两个值的总和。 例如，第 0 行到第 5 行是```
1
1 1
1 2 1
1 3 3 1
1 4 6 4 1
1 5 10 10 5 1
```输入是单个整数`n`，标识我们需要其最大值的行。 输出是最大值，而不是整行。 

Codeforces 语句当前指定了一秒的时间限制和 256 MB 的内存，但可访问语句并未发布上限`n`。 缺失的界限不会改变数学解。 显式构造所有行的方法`n`执行二次加法，而帕斯卡三角形的有用结构让我们只计算线性算术步骤中的中间系数。 

有两个索引细节很容易导致错误答案。 第一个是顶行是第 0 行。对于输入`0`，唯一的值是`1`，所以输出是`1`。 将输入视为基于 1 的行号的解决方案会意外检查第二行，这也恰好给出`1`，隐藏了这种特殊情况下的索引错误。 

第二个问题是奇数行有两个相等的中心值。 用于输入`5`，该行是`1 5 10 10 5 1`，所以答案是`10`。 使用非中心位置的解决方案，例如`n // 2 - 1`对于某些偶数行仍然可以工作，但对于最小的奇数行可能会失败。 例如，输入`3`产生`1 3 3 1`，其正确答案是`3`。 

最后一个边缘情况是 row`1`，其中每个值都相等。 输入```
1
```有输出```
1
```假设总是有一个内部元素的粗心实现将会失败，因为该行只有两个边界值。 

## 方法

 直接的方法是逐行构造帕斯卡三角形。 我们从`[1]`，从相邻对生成下一行，并继续直到行`n`。 这是正确的，因为构造规则正是帕斯卡三角形的定义。 然而，当我们只想要一行的最大值时，没有必要生成每个值。 

到达行`n`，该结构的性能大致为

 [
 1 + 2 + \cdots + n = \frac{n(n+1)}{2}
 ]

 价值创造运营。 因此最坏情况的运行时间是`O(n^2)`，最后一行本身包含`n + 1`价值观。 如果`n`很大时，首先要消除二次运算次数。 

关键的观察来自于将每个条目识别为二项式系数。 位置`k`在行中`n`是

 [
 \binom{n}{k}。 
]

 当我们向行中间移动时，系数会增加，然后对称地减少。 从代数上来说，

 \frac{n-k}{k+1}。 
]

 只要`k < n/2`，该比率大于或等于`1`，因此系数不会减小。 中间之后，对称

 [
 \binom{n}{k} = \binom{n}{n-k}
 ]

 接管。 因此，最大值始终是中心系数

 [
 \binom{n}{\lfloor n/2 \rfloor}。 
]

 我们现在只需计算一个二项式系数。 从乘法公式计算它可以避免构建整个三角形：

 \prod_{i=1}^{k}\frac{n-k+i}{i},
 \qquad
 k=\left\lfloor\frac n2\right\rfloor。 
]

 每次迭代中的每次除法都是准确的，因为运行值本身就是二项式系数。 Python 的任意精度整数还允许精确表示结果，而不会出现固定宽度整数溢出。 

蛮力方法之所以有效，是因为它直接遵循帕斯卡递归，但它对前面每一行中的每个值都进行了工作。 只有中心系数才能最大的观察结果减少了构造问题`Θ(n²)`进入计算领域`Θ(n)`精确的乘法更新。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 对于大型来说太慢`n`|
 | 最佳 | O(n) 次算术迭代 | O(1) 辅助空间 | 已接受 |

 上述复杂性将算术更新视为恒定时间操作。 由于答案本身呈指数增长`n`，它的整数表示也会增长，因此实际的位复杂度必然包括操作大整数的成本。 

## 算法演练

 1.读取请求的行号`n`。 该行的索引为零，因此 row`n`包含的系数`(1+x)^n`。 
2. 设置`k = n // 2`。 最大系数出现在该位置。 对于奇数`n`，两个中间系数相等，因此任一中间位置都会给出相同的答案。 
3. 初始化`value = 1`，代表第一个系数，`C(n, 0)`。 
4. 对于每一个`i`从`1`通过`k`，使用更新系数

 \binom{n}{i-1}\frac{n-i+1}{i}。 
]

 乘法和除法按以下顺序执行：```
value = value * (n - i + 1) // i
```划分是准确的，因为`value * (n-i+1) / i`正是下一个二项式系数。 

1. 循环结束后，`value`等于`C(n, k)`，这是行中的最大值`n`。 打印出来。 

### 为什么它有效

 不变量是迭代后`i`,`value`正是`C(n, i)`。 最初这是真的，因为`C(n, 0) = 1`。 如果`value = C(n, i-1)`，更新给出

 # \frac{n!}{i!(n-i)!}

 C(n,i)。 
]

 因此，不变量在整个循环中保持不变。 什么时候`i = floor(n/2)`，该值为中心二项式系数。 帕斯卡三角形是对称的，其系数到中间为止都是不减的，因此该系数是整行中最大的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    k = n // 2
    value = 1

    for i in range(1, k + 1):
        value = value * (n - i + 1) // i

    print(value)

if __name__ == "__main__":
    solve()
```输入仅包含一个整数，因此`solve`不需要测试用例循环。 表达式`n // 2`使用整数算术选择中心位置，并且适用于偶数行和奇数行。 

循环开始于`1`因为`C(n, 0)`已经被初始化为`1`。 其上端点为`k`，包含在内，因此可以准确计算所需的中心系数。 递归使用`n - i + 1`， 不是`n - i`，因为从`C(n, i-1)`到`C(n, i)`介绍该特定分子。 

Python 整数会自动扩展以适应可能非常大的答案。 在固定宽度整数类型的语言中，溢出需要单独考虑，但在Python中没有这样的问题。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) 次算术迭代 | 只有第一个`floor(n/2)`系数是通过乘法递归生成的 |
 | 空间| O(1) 辅助空间 | 仅有的`n`,`k`,`i`，当前系数被存储 |

 已发表的声明给出了一秒的限制，但目前忽略了数字上限`n`。 在线性迭代可行的任何正常比赛大小的界限下，这避免了整个三角形的二次构造。 答案本身可能比机器整数大得多，Python 的任意精度整数可以准确地处理这个问题。

## 边缘情况

 对于行`0`，确切的输入是```
0
```算法集`k = 0`，因此循环执行零次并打印初始值`1`。 这是正确的，因为帕斯卡三角形从单个系数开始`C(0,0) = 1`。 

对于行`1`，输入是```
1
```这里`k = 0`，所以同样不需要循环迭代。 结果是`1`，匹配行`1 1`。 这处理仅边界行而不假设存在内部系数。 

对于奇数行，例如```
3
```该算法计算`k = 1`并获得

 [
 \binom31=3。 
]

 完整的行是`1 3 3 1`，因此第二个中心值具有相同的最大值。 选择`floor(n/2)`就足够了，因为对称性保证了另一个中心位置具有完全相同的值。 

对于偶数行，例如```
6
```该算法计算`k = 3`并获得

 [
 \binom63=20。 
]

 该行是`1 6 15 20 15 6 1`，所以中心系数是唯一的最大值。 循环恰好到达该位置并停止，从而避免了对称一半的不必要的计算。 

对于大行，数值可能会大大超出标准 32 位或 64 位整数范围。 Python 将系数存储为任意精度整数，因此递归保持精确。 不使用浮点计算，这也避免了可能破坏二项式系数的舍入误差。 

核心数学特性是中点之前的每个系数至少与前一个系数一样大，而对称性则镜像中点之后的这些系数。 这个单一的属性让算法可以忽略每个非中心位置，而不会冒最大的风险。
