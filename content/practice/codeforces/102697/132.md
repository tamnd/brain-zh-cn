 ## 解决方案
 ## 问题理解

 我们需要在从 (0) 到 (C) 的区间上对用户提供的函数 (f(x)) 下的面积进行数值近似。 该函数以包含变量的算术表达式给出`x`、数字、括号、加法、减法、乘法、除法和指数`^`。 乘法也可以隐式地写成，如`5x`。 

所需的近似具体是左矩形近似法。 The interval is split into exactly (N=50000) equal-width rectangles. 每个矩形的宽度为(C/N)，矩形(k)的高度为(f(kC/N))，对于(k=0,\ldots,N-1)。 因此我们需要的数量是

 [
 A=\frac{C}{N}\sum_{k=0}^{N-1}f\left(\frac{kC}{N}\right)。 
]

 官方问题指定（N=50000）并给出了10秒的时间限制，内存为256MB。 评估点的固定数量足够大，以至于重复解析表达式的成本太高。 该表达式必须解析一次，转换为可以重复计算的形式，然后计算 50000 次。 

主要的非平凡约束不是（C）的大小，而是重复的函数评估。 如果表达式包含 (m) 个运算符和操作数，则在每个样本点独立评估它的成本为 (O(50000m))。 对于大小合理的表达式来说，这是可以接受的，但从头开始解析或解释原始字符串 50000 次会增加不必要的开销。 

已发布的示例中还存在一个微妙的问题。 第二个官方样本是```
(x^2 + x + 3) / (x^3 + x^2 + 5x)
7
```带输出`0.9806709605550483`。 根据所述的 LRAM 定义，(f(0)) 是未定义的，因为分母为零，并且从零开始的数值积分也具有对数奇点。 因此，该样本在数学上无法与当前语句中打印的公式相对应。 第一个和第三个样本与规定的LRAM公式一致。 这似乎是存档问题陈述中的错误，因此实现应该遵循正式定义，而不是为矛盾的样本发明特殊行为。 

对于有效表达式，边缘情况是常量函数。 例如，```
5
2
```有 (f(x)=5)，所以每个矩形的高度为 5，答案正是`10`。 不小心只评估端点的粗心实现仍然会在这里起作用，这可能会隐藏不正确的采样策略。 

另一个有用的边界情况是值在零附近快速变化的函数。 为了```
x^2
1
```第一个左边的样本正好是 (x=0)，因此它的高度为零。 其余样本接近正确端点，但从未包含它。 右端点实现将计算不同的近似值，即使随着矩形数量的增加，两种方法都收敛到相同的积分。 

## 方法

 直接暴力方法将重复读取表达式并针对 (x) 的每个值解释它。 这是正确的，因为每次评估都准确计算 LRAM 公式所需的矩形高度。 问题是相同的语法工作被执行了 50000 次。 如果表达式有 (m) 个标记，则仅用于解释就会花费 (O(50000m))，并且还会因重复扫描和解析字符串而产生额外开销。 如果递归地重新解析子字符串，更粗心的蛮力可能会变得更糟，可能接近 (O(50000m^2))。 

有用的观察是表达式本身永远不会改变。 仅分配给的值`x`变化。 我们可以解析一次表达式并将其转换为逆波兰表示法，也称为后缀表示法。 例如，```
x^3 + 2*x
```在概念上变得```
x 3 ^ 2 x * +
```后缀序列包含表达式的完整结构，因此将其评估为新值`x`只需要一个浮点值堆栈。 初始转换后无需进行解析。 

解析器还处理隐式乘法。 当一个产生价值的代币后面紧跟着另一个产生价值的代币时，例如`5x`或者`2(x+1)`，自动插入乘法。 这很重要，因为只处理显式的`*`因为乘法会错误地解析有效输入。 

生成的算法解析一次，计算后缀表达式 50000 次，并累加矩形高度。 这两种方法可以进行如下比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 重新解析每个样本的表达式 | (O(Nm)) 或更糟，具体取决于解析器 | (O(米)) | 太慢而且没必要 |
 | 解析一次，评估 postfix | (O(m + Nm)) | (O(米)) | 已接受 |

 这里 (m) 是表达式的大小，(N=50000)。 

## 算法演练

 1. 读取表达式和值 (C)。 解析时表达式必须保持完整，因为空格与算术语法无关，因此解析器首先删除空格。 
2. 将表达式分词为数字、变量`x`、运算符和括号。 即使数字包含多个数字，也将被视为一个标记。 
3. 根据正常算术优先级解析标记。 加法和减法的优先级最低，乘法和除法次之，求幂的优先级较高。 括号覆盖这些规则。 
4. 解析乘法时，认识显式乘法和隐式乘法。 例如，读完后`5`, 下一个标记`x`开始另一个因素，因此解析器将序列解释为`5 * x`。 相同的规则允许诸如以下的表达式`2(x+1)`。 
5. 将解析后的表达式转换为后缀表示法。 运算符放置在其操作数之后，因此计算不再需要做出任何优先级决定。 
6. 设置（N=50000）并计算公共矩形宽度为（C/N）。 对于从 0 到 (N-1) 的每个 (k)，计算 (x=kC/N)。 
7. 使用该值计算后缀表达式`x`。 一个数字将其值压入堆栈，`x`推送当前样本坐标，运算符弹出其操作数，执行操作并推送结果。 
8. 将评估的高度添加到运行总和中。 由于每个矩形都具有相同的宽度，因此最终面积是所有高度之和乘以 (C/N)。 
9. 打印生成的浮点值。 法官使用近似比较，因此不要求再现特定的小数位数。 

为什么有效：解析后，后缀表达式表示与输入完全相同的算术表达式。 计算堆栈保持这样一个不变式：在处理后缀表达式的任何前缀后，堆栈上的每个值都是一个已经完成的子表达式的结果。 因此，当处理运算符时，其操作数正是该运算符所需的值。 因此，每次评估都会返回当前样本点的 (f(x))。 外循环精确计算 50000 个左端点 (kC/N)，因此将它们的总和乘以 (C/N) 即可准确得出问题指定的 LRAM 近似值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

N = 50000

def tokenize(s):
    s = ''.join(s.split())
    tokens = []
    i = 0

    while i < len(s):
        c = s[i]

        if c.isdigit() or c == '.':
            j = i
            while j < len(s) and (s[j].isdigit() or s[j] == '.'):
                j += 1
            tokens.append(('num', float(s[i:j])))
            i = j

        elif c == 'x':
            tokens.append(('x', None))
            i += 1

        else:
            tokens.append((c, None))
            i += 1

    return tokens

def is_value_end(token):
    return token[0] in ('num', 'x', ')')

def is_value_start(token):
    return token[0] in ('num', 'x', '(')

def to_postfix(tokens):
    output = []
    operators = []

    precedence = {
        '+': 1,
        '-': 1,
        '*': 2,
        '/': 2,
        '^': 3,
        'u+': 4,
        'u-': 4,
    }

    right_assoc = {'^', 'u+', 'u-'}

    prev = None

    for token in tokens:
        typ = token[0]

        if typ == 'num' or typ == 'x':
            if prev is not None and is_value_end(prev):
                while operators and operators[-1] != '(':
                    top = operators[-1]
                    if (
                        precedence[top] > precedence['*']
                        or (
                            precedence[top] == precedence['*']
                            and '*' not in right_assoc
                        )
                    ):
                        output.append(operators.pop())
                    else:
                        break
                operators.append('*')

            output.append(token)
            prev = token
            continue

        if typ == '(':
            if prev is not None and is_value_end(prev):
                while operators and operators[-1] != '(':
                    top = operators[-1]
                    if precedence[top] >= precedence['*']:
                        output.append(operators.pop())
                    else:
                        break
                operators.append('*')

            operators.append('(')
            prev = token
            continue

        if typ == ')':
            while operators and operators[-1] != '(':
                output.append(operators.pop())
            operators.pop()
            prev = token
            continue

        if typ in '+-':
            unary = prev is None or prev[0] in ('+', '-', '*', '/', '^', '(')
            op = 'u+' if unary and typ == '+' else 'u-' if unary else typ

            while operators and operators[-1] != '(':
                top = operators[-1]
                if (
                    precedence[top] > precedence[op]
                    or (
                        precedence[top] == precedence[op]
                        and op not in right_assoc
                    )
                ):
                    output.append(operators.pop())
                else:
                    break

            operators.append(op)
            prev = (op, None)
            continue

        if typ in '*/^':
            op = typ

            while operators and operators[-1] != '(':
                top = operators[-1]
                if (
                    precedence[top] > precedence[op]
                    or (
                        precedence[top] == precedence[op]
                        and op not in right_assoc
                    )
                ):
                    output.append(operators.pop())
                else:
                    break

            operators.append(op)
            prev = token
            continue

    while operators:
        output.append(operators.pop())

    return output

def evaluate(postfix, x):
    stack = []

    for token in postfix:
        typ = token[0]

        if typ == 'num':
            stack.append(token[1])
        elif typ == 'x':
            stack.append(x)
        elif typ == 'u+':
            stack[-1] = +stack[-1]
        elif typ == 'u-':
            stack[-1] = -stack[-1]
        else:
            b = stack.pop()
            a = stack.pop()

            if typ == '+':
                stack.append(a + b)
            elif typ == '-':
                stack.append(a - b)
            elif typ == '*':
                stack.append(a * b)
            elif typ == '/':
                stack.append(a / b)
            else:
                stack.append(a ** b)

    return stack[0]

def solve():
    expression = input().strip()
    C = float(input())

    tokens = tokenize(expression)
    postfix = to_postfix(tokens)

    width = C / N
    total = 0.0

    for k in range(N):
        x = k * width
        total += evaluate(postfix, x)

    print(total * width)

if __name__ == "__main__":
    solve()
```分词器会删除空格，因为空格在表达式中没有数学意义。 然后，它将连续的数字分组为单个数字标记并处理`x`分别地。 

到后缀的转换是解决优先级的地方。 括号保留在运算符堆栈中，直到出现匹配的右括号为止。 求幂是右结合的，因此诸如`x^2^3`被解释为 (x^{(2^3)})，而不是 ((x^2)^3)。 

一元符号与二进制加法和减法分开处理。 这允许诸如以下的表达式`-x`,`x*-2`， 和`-(x+1)`的表示不会将一元减法与减法混淆。 

评估函数故意接收`x`作为参数而不是修改后缀表达式。 因此，所有 50000 个样本点都会重复使用相同的解析表达式。 

循环使用`range(N)`， 不是`range(1, N)`，因为 LRAM 对每个矩形的左端点进行采样。 最后采样的坐标是`(N-1)*C/N`，因此不评估右端点 (C)。 乘以`width`求和之后只发生一次，这在代数上相当于将每个矩形单独相乘。 

Python 的浮点数为任务的近似性质提供了足够的精度。 Python 整数也是无界的，因此在读取数字常量时不存在整数溢出问题，尽管数字文字会转换为浮点数进行计算。

 | ---| ---| ---|
 | 时间 | (O(m + Nm)) | 表达式被解析一次，然后为每个 (N=50000) 个样本点处理最多 (m) 个后缀标记。 |

 ## 边缘情况

 恒定的函数不需要特殊处理。 对于准确的输入```
5
2
```解析器创建单个数值。 50000 次评估中的每一次都返回 5，累积高度为 250000，乘以宽度 (2/50000) 正好得到 10。该算法从不假设`x`出现在表达式中。 

包含隐式乘法的表达式也需要显式解析器支持。 为了```
2(x + 1)
3
```解析器在之间插入乘法运算符`2`和`(`。 生成的函数为 (2(x+1))，其从 0 到 3 的积分为 15。仅识别文字的解析器`*`要么拒绝这个表达式，要么错误地解释它。 

左端点是另一个边界条件。 为了```
x^2
1
```第一个评估使用 (x=0)，高度为零。 最终评估使用(x=49999/50000)，而不是(x=1)。 由此产生的 LRAM 估计值略低于精确积分 (1/3)，这是递增函数的左端点近似的预期行为。 

一元减法也可能暴露解析器错误。 和```
-(x + 1)
2
```解析器必须处理第一个`-`作为一元运算符而不是作为二进制减法。 每个评估的高度均为负值，数值面积约为 (-4)。 将前导减号视为二元运算符将使表达式没有左操作数。 

最后，在验证解决方案时，发布的第二个示例值得特殊处理。 它的分母在 (x=0) 处计算为零，而函数的行为类似于 (3/(5x)) 接近零。 因此，所述 LRAM 公式无法产生已发布的有限值`0.9806709605550483`。 对这种不一致的正确反应是遵循正式算法和有效的测试数据，而不是添加会改变数学问题的特定于样本的异常。
