 ## 解决方案
 ## 问题理解

 每行都以以下形式给出

 [
 y = mx + b
 ]

 其中 (m) 是其斜率，(b) 是其 (y) 截距。 输入包含一行第一行的两个系数和下一行第二行的两个系数。 

任务是找到两条线相交点的 (x) 坐标。 该问题保证两条线确实相交，因此我们不需要处理平行线或相同线。 

已发布的问题使用一秒的时间限制和 256 MB 的内存。 这里没有大的（n）、数组、图形或重复的测试用例参数。 输入仅包含四个浮点值，因此预期的解决方案应该执行恒定数量的算术运算。 任何运行时间取决于尝试许多可能的 (x) 坐标的算法都是不必要的。 

主要的边缘情况来自代数而不是输入大小。 首先，交点可以具有负 (x) 坐标。 例如，```
5 3
-6 -20
```产生```
-2.090909090909091
```因为这些线与 (y) 轴的左侧相交。 假设答案必须非负的实现是不正确的。 

第二种情况是当斜坡彼此非常接近时。 例如，```
1.000001 2
1 1
```有

 [
 x = \frac{1-2}{1.000001-1} = -1000000。 
]

 分母很小，因此在执行除法之前对斜率进行过度舍入可能会显着改变答案。 

第三种情况是一个或两个截距为零时。 例如，```
2 0
-1 3
```给出

 [
 2x=-x+3,
 ]

 所以（x=1）。 将零视为缺失值或依赖于非零截距的特殊处理的解决方案将不必要地失败。 

最后，在问题的交集保证下，两个斜率不能相等。 例如，如果两条线都有斜率 (2)，```
2 1
2 5
```将代表平行线并且没有交点。 我们不需要为这种情况发明输出，因为该语句保证提供的每对线都相交。 

## 方法

 暴力方法可以通过数字方式搜索 (x) 坐标。 对于选定的精度（\varepsilon），我们可以在连续的（x）值处评估两条线，并寻找它们的（y）值变得足够接近的点。 从概念上讲，这是可行的，因为两条相交线在其交点处具有相等的 (y) 值。 

问题在于，这将直接的代数问题变成了任意的数值搜索。 如果搜索覆盖长度 (R) 和间距 (\varepsilon) 的区间，则需要

 [
 \left\lceil\frac{R}{\varepsilon}\right\rceil+1
 ]

 最坏情况下的候选人评价。 该语句没有提供有限的搜索间隔或所需的离散化，这使得这种方法更可取。 更糟糕的是，使 (\varepsilon) 变小会增加运算次数，而不会给出精确的代数答案。 

关键的观察结果是，在交点处，两个方程具有相同的 (y) 值。 如果线路是

 [
 y=m_1x+b_1
 ]

 和

 [
 y=m_2x+b_2,
 ]

 我们可以简单地将它们的右侧设置为相等：

 [
 m_1x+b_1=m_2x+b_2。 
]

 将 (x) 项移至一侧并将常数移至另一侧给出

 [
 (m_1-m_2)x=b_2-b_1。 
]

 由于线保证相交，(m_1-m_2\neq0)，所以

 [
 x=\frac{b_2-b_1}{m_1-m_2}。 
]

 蛮力之所以有效，是因为它在数值上精确地搜索这个等式，但未能利用这个等式可以直接求解的事实。 代数将整个问题简化为一次分子减法、一次分母减法和一次除法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(R/\varepsilon)) | (O(1)) | (O(1)) | 太慢且依赖精度 |
 | 最佳 | (O(1)) | (O(1)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 读取第一行的斜率和截距 (m_1) 和 (b_1)，以及第二行的相应值 (m_2) 和 (b_2)。 
2. 将两个直线方程设置为相等，因为它们交点处的 (y) 坐标相同。 

[
 m_1x+b_1=m_2x+b_2。 
]
 3. 重新排列方程以分离 (x)。 

[
 (m_1-m_2)x=b_2-b_1。 
]

 该问题保证相交，因此斜率不可能相等。 因此除以 (m_1-m_2) 是有效的。 
4. 计算

 [
 x=\frac{b_2-b_1}{m_1-m_2}。 
]
 5. 打印生成的浮点值。 Python 的浮点表示足以解决这个问题，并且 Python 的`str`conversion 打印合适的十进制表示形式，而不需要我们选择任意数量的小数位数。 

关键的不变量是通过使两条直线相等而得到的方程。 在每个可以交集的点，(y) 的两个表达式必须具有相同的值。 代数变换保持相等，因此 (x) 的最终值正是满足两个直线方程的唯一坐标。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    m1, b1 = map(float, input().split())
    m2, b2 = map(float, input().split())

    x = (b2 - b1) / (m1 - m2)
    print(x)

if __name__ == "__main__":
    solve()
```第一个输入行被解析为`m1`和`b1`，匹配第一个方程 (y=m_1x+b_1)。 第二行以同样的方式解析。 

表达式`(b2 - b1) / (m1 - m2)`直接遵循推导公式即可。 严格遵守书面的减法顺序。 将分子更改为`b1 - b2`如果不改变分母就会否定答案。 

蟒蛇的`float`使用 type 是因为输入由浮点值组成。 尽管浮点运算仍然具有通常的有限精度行为，但 Python 不存在固定宽度整数语言中会出现的整数溢出问题。 在计算交点之前没有理由对系数进行舍入，因为当斜率接近时这样做可能特别有害。 

也不需要循环，因为问题恰好包含一对线而不是多个测试用例。 源问题明确描述了两个输入行和一个输出值。

## 边缘情况

 负坐标情况的处理无需任何特殊分支。 为了```
5 3
-6 -20
```该算法计算 (b_2-b_1=-23) 和 (m_1-m_2=11)，给出 (x=-23/11)。 负分子自然会产生正确的负坐标。 

零截距的情况同样直接。 为了```
2 0
-1 3
```分子为(3-0=3)，分母为(2-(-1)=3)，所以结果为(1)。 将 (x=1) 代入两个方程得出 (y=2)，从而确认交集。 

接近斜率的情况说明了为什么解决方案不应使用搜索或过度舍入系数。 和```
1.000001 2
1 1
```分母仅为 (0.000001)。 公式给出

 [
 x=\frac{1-2}{1.000001-1}
 =\frac{-1}{0.000001}
 =-1000000。 
]

 如果搜索范围太小，粗略的数值搜索可能会完全错过这个交点，而直接公式可以立即获得它。 

最后，输入保证排除了相等的斜率。 为了```
2 1
2 5
```分母为零，代表平行线。 该程序不会为这种情况添加特殊输出，因为法官从不提供它。 添加任意分支实际上可能会掩盖问题的核心保证，即每个输入都由两条相交线组成。
