 ## 问题理解

 我们有一个单词拼写错误`w`和一本包含`n`候选词。 对于每个字典单词`s`，我们比较每个字符`w`与每个字符`s`。 当两个字符相等时，一对将精确地贡献一次匹配。 

如果`|w| = a`和`|s| = b`，正好有`a * b`字符对。 如果`mat`这些对包含相同的字符，相似度指数为`mat / (a * b)`。 

任务是打印每个字典单词及其相似度索引，四舍五入到小数点后两位。 主要排序是相似性递减。 如果两个单词具有完全相同的相似度索引，则按字母顺序排列在后的单词排在前面。 该问题使用一秒限制和 256 MB 内存。 已发表的声明没有提供明确的字长上限或`n`，所以有用的解释是，解决方案应该避免做与每个单词对的长度的乘积成比例的工作。 

字母表固定为 26 个小写字母。 这种限制是我们可以利用的关键结构性约束。 一旦我们知道每个字母出现了多少次`w`在字典单词中，我们可以计算所有匹配的字符对，而无需显式检查每一对。 

有几种边缘情况可能会导致看似合理的实现出现错误。 首先，角色位置并不重要。 例如，与```
ab
1
ba
```两对`(a,b)`,`(a,a)`,`(b,b)`， 和`(b,a)`包含两个匹配项，所以答案是```
ba 0.50
```位置比较会错误地找不到匹配项。 

另一个边缘情况是重复的字符会产生重复的对。 和```
aaa
1
aa
```三者中的每一个`a`第一个单词中的字符与两者都匹配`a`第二个单词中的字符。 有`3 * 2 = 6`成对且所有六组都匹配，所以结果是```
aa 1.00
```计算不同字母而不是出现次数会给出错误的分子。 

排序规则还有一个微妙的结果。 考虑```
ab
2
aa
bb
```两个候选者在四个匹配对中都有两个匹配对，因此两者都有相似性`0.50`。 按字母顺序逆序看跌期权`bb`前`aa`:```
bb 0.50
aa 0.50
```正常的按字母顺序升序的抢七会默默地颠倒这两个答案。 

最后，必须使用它们的实际分数而不是打印的两位小数表示来比较看起来相同的十进制值。 两个不同的相似度分数都可以舍入为`0.12`，而排序规则是基于原始相似度指数。 因此，排序前的舍入可能会产生错误的顺序。 

## 方法

 直接解法遵循字面定义。 对于每个字典单词`s`，迭代每个字符`w`以及每一个角色`s`，计算相等的对，并将该计数除以`|w| * |s|`。 如果`a = |w|`字典单词长度是`b_1, b_2, ..., b_n`，字符比较的数量正好是`a * b_1 + a * b_2 + ... + a * b_n`。 

如果所有字典单词都有长度`L`， 这是`n * a * L`比较。 这正是配对检查部分最坏情况下的操作计数。 由于该声明没有公布这些长度的最大值，因此没有单个数字的最坏情况计数可以替代，但对两个字长的乘法依赖性是问题所在。 对结果进行排序`n`记录额外费用`O(n log n)`。 

蛮力方法是正确的，因为它直接精确地计算定义所使用的对。 它的弱点是大多数比较都是不必要的。 例如，如果`w`包含 10,000 个字符，将其与另一个 10,000 个字符的单词进行比较需要 1 亿个字符比较，尽管唯一需要的信息是有多少个字符`a`s，有多少个`b`s 等出现在每个单词中。 

关键的观察是每个匹配对仅由其特征决定。 认为`w`包含`cnt_w[c]`角色的副本`c`， 和`s`包含`cnt_s[c]`副本。 每次出现`c`在`w`可以与每次出现的`c`在`s`, 给予`cnt_w[c] * cnt_s[c]`匹配对。 将 26 个小写字母相加即可得出整个分子：`mat = Σ cnt_w[c] * cnt_s[c]`。 

我们可以构建频率数组`w`一次。 然后，每个字典单词只需要遍历它自己的字符一次即可构建其 26 频率数组，然后进行 26 次乘法。 对字长的成对依赖消失了。 

排序步骤中还有另一个有用的细节。 相似度是分数`mat / tot`。 比较两个分数`a / b`和`c / d`不需要浮点运算。 我们可以比较一下`a * d`和`c * b`。 即使十进制表示形式很接近，这也能给出精确的排序。 

暴力破解之所以有效，是因为它显式地枚举了每个有效的字符对，但当字长的乘积变大时就会失败。 观察到匹配对可以按其特征进行分组，从而将每次比较减少到 26 个频率乘积，之后仅保留字典排序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(Σ | w | · | s_i | + n log n)`|`O(n)`| 当单词很长时太慢 |
 | 最佳|`O(Σ | s_i | + 26n + n log n)`|`O(n + 26)`| 已接受 |

 这里`Σ |s_i|`是所有字典单词中的字符总数。 固定因子 26 可以被视为常数，给出`O(Σ |s_i| + n log n)`。 

## 算法演练

 1.读出拼写错误的单词`w`并统计 26 个小写字母中每一个的出现次数。 计数数组总结了有关的所有内容`w`这与相似度计算有关。 
2. 阅读字典中的每一个单词`s`并计算其字符频率。 单次扫描`s`就足够了，因为其字符的位置永远不会影响相似性。 
3. 通过求和计算匹配字符对的数量`cnt_w[c] * cnt_s[c]`全部 26 个字母。 该产品计算由出现的每个可能的对组成的`c`在`w`以及发生`c`在`s`。 
4. 将分母设置为`len(w) * len(s)`。 的每一个角色`w`与每个角色配对`s`，无论字符是否匹配。 
5. 存储单词、其分子和分母。 保留分数而不是仅保留浮点值可以让我们准确地对相似性进行排序。 
6. 通过比较分数对字典记录进行排序`mat1 / tot1`和`mat2 / tot2`。 为了减少相似度，具有较大叉积的记录`mat1 * tot2`首先。 当分数相等时，按相反的字母顺序比较单词。 
7. 将每个单词及其分数打印为小数，小数点后精确到两位数。 浮点转换仅用于在已经做出准确排序决策之后的格式化。 

### 为什么它有效

 对于任何字典单词`s`, 考虑一个字符`c`。 有`cnt_w[c]`的出现次数`c`在`w`和`cnt_s[c]`出现在`s`。 第一组中的每个出现都可以与第二组中的每个出现配对，因此正好有`cnt_w[c] * cnt_s[c]`其字符为的匹配对`c`。 每个匹配对都属于一个字符组，因此对所有 26 个字母的这些乘积求和会将每个匹配对恰好计数一次。 分母计算每个可能的对，从定义中准确给出相似性指数。 

存储的分数是精确的相似度，因此交叉乘法给出与比较实值相似度相同的排序，而不会引入浮点错误。 仅当两个分数完全相等时才使用二次比较，这符合所需的反向字母顺序抢七。 

## Python 解决方案```python
import sys
from functools import cmp_to_key

input = sys.stdin.readline

def compare(a, b):
    # a = (word, numerator, denominator)
    # b = (word, numerator, denominator)

    left = a[1] * b[2]
    right = b[1] * a[2]

    if left != right:
        # Higher similarity first.
        return -1 if left > right else 1

    # Equal similarity: reverse alphabetical order.
    if a[0] == b[0]:
        return 0
    return -1 if a[0] > b[0] else 1

def solve():
    w = input().strip()
    n = int(input())

    freq_w = [0] * 26
    for ch in w:
        freq_w[ord(ch) - ord('a')] += 1

    results = []

    for _ in range(n):
        s = input().strip()

        freq_s = [0] * 26
        for ch in s:
            freq_s[ord(ch) - ord('a')] += 1

        matches = 0
        for i in range(26):
            matches += freq_w[i] * freq_s[i]

        total = len(w) * len(s)
        results.append((s, matches, total))

    results.sort(key=cmp_to_key(compare))

    for word, matches, total in results:
        similarity = matches / total
        print(f"{word} {similarity:.2f}")

if __name__ == "__main__":
    solve()
```第一个频率数组只构建一次，因为每个字典比较都会共享拼写错误的单词。 其建设需要`O(|w|)`时间。 

对于每个字典单词，第二个频率数组用 26 个零进行初始化，并通过扫描该单词一次进行填充。 然后匹配对计算精确执行 26 次乘法和加法。 这是算法中频率公式的直接实现。 

比较函数故意基于整数乘法。 对于两个相似点`a / b`和`c / d`, 比较`a * d`反对`c * b`避免浮点精度问题。 Python 整数也会自动增长，因此当乘积变大时不存在整数溢出问题。 

抢七局使用`a[0] > b[0]`，它将字典顺序较大的单词放在前面。 这很容易意外逆转，因为 Python 的正常字符串排序是升序。 

分母是`len(w) * len(s)`，不是较短单词的长度，也不是不同字符的数量。 第一个单词中的每个字符都与第二个单词中的每个字符配对。 

仅当生成所请求的两位小数表示时才使用最终除法。 它不用于排序，因此由于浮点舍入，两个相近的分数无法重新排序。
