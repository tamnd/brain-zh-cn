 ## 解决方案
 ## 问题理解

 我们有一个（N \times N）棋盘，并且想要恰好放置（N）个皇后，以便没有两个皇后可以互相攻击。 皇后可以水平、垂直和对角攻击，因此每对皇后必须占据不同的行、不同的列和不同的对角线。 输出是满足这些条件的不同放置的总数。 输入仅包含 (N)。 

关键约束是 (N \le 9)。 这个值足够小，可以通过积极的修剪进行详尽的搜索，但也足够大，盲目地尝试每种板配置的成本都太高了。 如果我们在每一行中为皇后独立选择一列，则有 (N^N) 种可能的放置位置。 在 (N=9) 处，即 (9^9 = 387{,}420{,}489) 个候选者。 检查每个完整候选处的所有皇后对将需要最多 (\binom{9}{2}=36) 对检查，大约提供 (139.5) 十亿对检查。 五秒钟的解决方案无法承担如此大量的工作。 

有几个小案例暴露了常见的实施错误。 对于(N=1)，唯一的方格包含唯一的皇后，所以答案是1。```
1
```正确的输出是：```
1
```仅在进行另一次递归调用后才增加答案的粗心实现可能会意外返回 0，因为没有下一行要处理。 

对于(N=2)，没有有效的排列。```
2
```正确的输出是：```
0
```两个皇后必须使用不同的行和列，但在任何可能的对角线排列中，它们都会互相攻击。 仅检查行和列的代码会错误地计算两种排列。 

对于 (N=3)，答案也是零。```
3
```正确的输出是：```
0
```这捕获了正确处理列但对角线公式不正确的实现，特别是当两个对角线方向混淆时。 

样本 (N=8) 有 92 个有效排列。```
8
```正确的输出是：```
92
```官方问题使用（N=9）作为其最大的板尺寸，并明确需要一个实际的算法而不是硬编码的查找表。 

## 方法

 最直接的暴力就是逐行处理板子。 对于每一行，尝试所有 (N) 列，继续直到所有 (N) 行都有皇后，然后检查结果板是否有效。 这是正确的，因为每个可能的布局对于每一行都有一个列选择，因此搜索最终会考虑每个可能的棋盘。 

问题在于候选人的数量。 每 (N) 行中有 (N) 个选择，搜索包含 (N^N) 个完整的展示位置。 最多 (N=9)，即 387,420,489 个展示位置。 尽管其中许多立即无效，但等到董事会完成后再检查冲突的强力实现仍然可以支付所有费用。 

通过观察两个皇后永远不能共享一行，我们可以立即改进搜索。 不要考虑任意的​​棋盘位置，而是在每一行中放置一个皇后。 一旦新皇后攻击先前的皇后，我们也可以拒绝部分放置。 这会将搜索从所有 (N^N) 行列分配更改为针对部分布局的修剪搜索。 

还有另一个有用的观察。 一旦我们从上到下处理行，决定下一个皇后可以去哪里所需的唯一信息是哪些列和对角线已经被占用。 我们不需要完整的董事会。 由于 (N) 最多为 9，因此这些集合中的每一个都自然适合整数位掩码。 

对于每个递归状态，一位代表每一列。 设定位`cols`意味着该列已经包含皇后。 另外两个掩码代表当前受到下一行上方皇后攻击的对角线。 我们可以通过位运算一次性计算出每个合法列。 

认为`full`包含设置为 1 的最低 (N) 位。然后```
available = full & ~(cols | diag1 | diag2)
```恰好包含可以放置下一个皇后的列。 选择一组位给出了一种合法的选择。 放置皇后后，对角线蒙版会移动，因为下一行低一行。 

蛮力之所以有效，是因为它检查了每个可能的放置，但失败了，因为它探索了大量已经违反约束的放置。 观察到每个无效的部分放置都可以立即被丢弃，这让我们可以只搜索可行的前缀。 然后，位掩码可以以恒定的时间查找和更新可行的列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(N^N \cdot N^2)) | (O(N)) | 太慢了 |
 | 使用位掩码回溯 | (O(N!)) 最坏情况 | (O(N)) | 已接受 |

 (O(N!)) 界限是修剪搜索的保守上限，因为一旦固定了行，就不能重复使用任何列，沿着任何未修剪的排列最多留下 (N, N-1, \ldots, 1) 列选择。 对角修剪使实际搜索变得相当小。 

## 算法演练

 1. 阅读（N）并创建`full = (1 << N) - 1`。 最低 (N) 位现在为 1，代表所有板列。 
2. 使用空列和对角掩码在第 0 行开始递归搜索。 在行 (r) 处，递归状态表示皇后在行 (0) 到 (r-1) 中的有效放置。 
3. 计算`available = full & ~(cols | diag1 | diag2)`。 该掩码中的每个设置位代表未被占用且未被较早皇后对角攻击的列。 
4.如果`available`在所有行都被填充之前为零，停止该分支。 下一个女王没有法律地位，因此继续下去无法产生解决方案。 
5. 取一个可用位`bit = available & -available`。 这隔离了最低的合法列。 顺序无关紧要，因为每个合法分支最终都必须被计算在内，并且一次选择一位只是简单地枚举它们而不会重复。 
6. 删除该位`available`，然后递归地在该列中放置一个皇后。 列掩码变为`cols | bit`。 
7. 将对角攻击移至下一行。 第一个对角掩码向左移动，第二个对角掩码向右移动：```
next_diag1 = ((diag1 | bit) << 1) & full
next_diag2 = (diag2 | bit) >> 1
```移位是必要的，因为每当我们向下移动一行时，对角线就会水平移动一列。 

1. 什么时候`row == N`，每一行恰好包含一个皇后，并且所有三个掩码都保证不会有两个皇后发生冲突。 将答案加一。 

### 为什么它有效

 不变的是，每个递归调用都代表在所有先前处理的行中放置皇后，并且没有两个皇后互相攻击。`cols`记录每个被占用的列，而两个对角掩码记录下一行中对角受到攻击的每一列。 最后，`available`准确地包含了下一任女王的合法职位。 每个有效的完整放置都会在每一行选择这些合法位置之一，因此它永远不会被修剪。 每个无效位置都有​​两个皇后共享同一列或对角线，并且冲突的位置将从中删除`available`在它可以被选择之前。 因此，每个有效板都只计算一次，并且不会计算无效板。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    full = (1 << n) - 1
    answer = 0

    def backtrack(row, cols, diag1, diag2):
        nonlocal answer

        if row == n:
            answer += 1
            return

        available = full & ~(cols | diag1 | diag2)

        while available:
            bit = available & -available
            available -= bit

            backtrack(
                row + 1,
                cols | bit,
                ((diag1 | bit) << 1) & full,
                (diag2 | bit) >> 1
            )

    backtrack(0, 0, 0, 0)
    print(answer)

if __name__ == "__main__":
    solve()
```这`full`mask 恰好包含属于板的列。 对于（N=4），它是`1111`以二进制形式。 对于（N=8），它是`11111111`。 掩蔽用`full`换档后`diag1`防止移动超出右边缘的位影响后面的行。 

递归函数接收当前行和三个掩码。 没有单独的板阵列，因为一旦知道占用的列和对角线，板本身就不再需要。 

表达式`available & -available`隔离一组位。 这使得循环一次处理一个合法列。 减去该位会将其从剩余候选中删除，而不修改属于当前递归状态的掩码。 

递归调用中的左移和右移是很容易犯差一错误的地方。 放置在 (c) 列的皇后攻击下一行的 (c-1) 和 (c+1) 列，因此两个对角线方向必须朝相反方向移动。 这`& full`左移丢弃离开棋盘的攻击后。 

基本情况检查`row == n`，而不是`row == n - 1`。 此时，所有 (N) 行都已收到皇后，因此已经构建了一个完整的解决方案。 这也可以正确处理 (N=1)。 

Python整数不会溢出，因此可以直接累加答案。 对于这个问题，最大的答案只有 352 (N=9)，但使用整数计数器仍然是自然的实现。

 ## 边缘情况

 对于 (N=1)，确切的输入是`1`。 初始状态有`available = 1`，因此放置了唯一的皇后。 递归调用达到`row == 1`，增加答案，并返回 1。实现中没有特殊情况分支，这是更好的选择，因为正常递归已经处理最小的板。 

对于 (N=2)，确切的输入是`2`。 第一个皇后可以放置在任意一列中。 假设它被放置在第一列。 在下一行，第一列被列掩码阻挡，第二列被对角线掩码阻挡，没有留下可用位置。 对称分支以同样的方式失败，因此最终计数为 0。这捕获了跟踪列但忘记对角线的常见错误。 

对于 (N=3)，确切的输入是`3`。 有些分支可以存活两排，但所有可能的第三排位置最终都会被阻塞。 答案是 0。特别是，必须独立跟踪两个对角线方向，因为皇后可以从任一侧攻击下一行。 

对于 (N=4)，确切的输入是`4`。 搜索恰好找到两种排列，通常由行到列序列表示`2413`和`3142`。 位掩码搜索对两者都进行计数，因为它会探索每行的每个合法列，而在创建另一个递归级别之前，违反对角线的分支将被丢弃。 

对于 (N=8)，确切的输入是`8`，输出为 92。这个值足够大，可以进行大量回溯，同时保持在约束范围内。 在某些语言中，重复扫描整个板以检查冲突的解决方案在这种大小下仍然有效，但位掩码表示消除了重复扫描并干净地缩放到所需的最大值。 

对于 (N=9)，确切的输入是`9`，输出为 352。这是对性能最重要的边界情况。 该实现不分配（N \times N）板，在递归期间不复制部分板，并使用少量整数运算检查所有合法列。 已知的 9 个皇后总数为 352 个。
