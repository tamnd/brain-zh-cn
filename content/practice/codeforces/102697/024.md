 ## 解决方案
 ## 问题理解

 两支篮球队进行了一场比赛，我们获得了足够的统计数据来重建每支球队的最终得分。 对于每支球队，输入给出了投篮总数、三分球投篮数以及罚球数。 

投篮要么是两分球，要么是三分球。 由于篮子总数包括这两种类型，因此一支球队`b`总篮子数和`t`三分命中`b - t`两分球。 因此它的篮子得分是`2 * (b - t) + 3 * t`。 

添加`f`罚球给出完整得分：`2 * (b - t) + 3 * t + f`。 

这简化为`2 * b + t + f`。 任务只是计算两个团队的这个值并打印得分较大的团队的名称。 该声明保证分数不同，因此不存在平局需要解决。 

已发表的声明中没有明确的数字上限。 输入仅包含恒定数量的整数和字符串，因此预期的解决方案执行恒定数量的算术和字符串处理。 即使整数值非常大，也没有理由单独迭代篮筐、三分球或罚球。 在 Python 中，整数算术还可以避免在提供异常大的值时在固定宽度语言中出现的溢出问题。 

主要的边缘情况来自于正确解释篮子计数的含义。 一个常见的错误是将每个投篮视为两分，然后每投进三分球分别加三分。 这会重复计算三分球的两分部分。 

例如，考虑：```
A B
1 0
1 0
0 0
```团队`A`投中一球，而且那个篮子是三分球。 其得分为`3`， 尽管`B`有`0`，所以正确的输出是：```
A
```粗心的实现使用`2 * baskets + 3 * three_pointers`会给`5`为了`A`。 获胜者在这里碰巧保持正确，但计算出的分数是错误的，并且相同的错误可能会改变另一个输入的获胜者。 

罚球是另一个单独的得分类别。 例如：```
A B
0 0
0 0
5 4
```分数是`5`和`4`，所以正确的输出是：```
A
```仅考虑篮筐和三分球的实施会错误地得出两队得分为零的结论。 

最后，一支球队可以有很多普通的两分球而没有三分球。 例如：```
A B
3 2
0 0
0 0
```分数是`6`和`4`，所以正确的输出是：```
A
```三分球命中数并非投篮总数。 具体来说就是投进的球数相当于三分，剩下的投篮数相当于两分。 

## 方法

 暴力方法可以尝试一一重建得分事件。 例如，如果有`E`为事件总计评分，不必要的常规搜索可能会考虑每个事件的三个​​可能的分值，从而产生最多`3^E`可能的序列。 然后可以计算每个候选人和所选获胜者的最终分数。 如果考虑到每个可能的得分序列，这是正确的，因为实际的游戏是这些序列之一。 

问题是评分项目的顺序不包含影响最终得分的信息。 输入数据已经为我们提供了准确确定每支球队的两分球、三分球和罚球数所需的总计数。 因此，枚举它们可能的订单是浪费工作。 如果`E`很大，`3^E`搜索很快就会变得不可行，甚至不需要更仔细地限制蛮力枚举。 

关键的观察是，两指针的数量没有直接给出，但可以立即导出。 如果一个团队做出了`B`篮子总数和`T`其中有三分球，那么准确地说`B - T`是两分球。 因此得分为`2(B - T) + 3T + F`这简化为`2B + T + F`。 

一旦认识了这个公式，整个游戏就可以通过两次分数计算和一次比较来解决。 蛮力之所以有效，是因为它最终可以恢复相同的总数，但它会失败，因为它探索了答案不依赖的信息。 只有总得分才重要的观察结果将问题简化为常数时间算术。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 一般事件枚举中的 O(3^E) | O(E) | 太慢而且没必要 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读出两个队的名字。 它们在输入中的顺序决定了哪个分数属于哪个团队，因此我们将名称的顺序与所有后续统计数据保持相同。 
2. 读取两个篮子总数。 打电话给他们`b1`和`b2`。 这些计数包括两分球和三分球。 
3.读取两个三分球计数，`t1`和`t2`。 对于每支球队来说，普通两分球的数量是其总投篮数减去三分球数。 
4. 读取两次罚球计数，`f1`和`f2`。 罚球与投篮次数无关，因此直接计入得分。 
5. 使用以下公式计算每个团队的得分`2 * baskets + three_pointers + free_throws`。 这相当于明确地将两个指针计算为`2 * (baskets - three_pointers)`和三分球`3 * three_pointers`，但简化后的公式更短，避免了不必要的中间工作。 
6. 比较两个分数。 由于声明保证有赢家，因此不需要处理平等。 打印出较大分数对应的名称。 

### 为什么它有效

 对于每个团队，让`B`是篮子的总数，`T`是其三分球的数量。 确切地`B - T`篮下都是两分球，所以篮下贡献为`2(B - T) + 3T`。 添加`F`罚球给予`2B + T + F`。 因此，该算法计算出每个团队的准确最终得分。 由于获胜者正是最终得分较高的球队，因此比较这两个计算值总是会产生所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    teams = input().split()

    baskets = list(map(int, input().split()))
    threes = list(map(int, input().split()))
    free_throws = list(map(int, input().split()))

    score1 = 2 * baskets[0] + threes[0] + free_throws[0]
    score2 = 2 * baskets[1] + threes[1] + free_throws[1]

    if score1 > score2:
        print(teams[0])
    else:
        print(teams[1])

if __name__ == "__main__":
    solve()
```第一行存储为`teams`，保存每个球队的名称和统计数据之间的对应关系。 接下来的三行将转换为整数列表，因为所有评分信息都是数字。 

分数计算使用简化表达式`2 * baskets + threes + free_throws`。 开始于`2 * baskets`将每个篮筐视为两分球。 每个三分球都需要加一分，因为它值三分而不是两分，所以加上`threes`准确地纠正那些篮子。 然后分别添加罚球。 

各个评分事件没有循环，因为输入已经提供了它们的总计计数。 也不存在超出固定头寸的指数边界问题`0`和`1`，因为恰好有两支球队在场。 

Python 的整数可以表示受可用内存限制的任意大的值，因此算术不需要任何特殊的溢出处理。 这个问题也保证了获胜者，允许`else`分支来安全地代表第二支球队，而无需单独的平等案例。

 ## 边缘情况

 第一个不明显的案例是一支唯一得分来自三分球的球队。 考虑：```
A B
1 0
1 0
0 0
```为了`A`，公式给出`2 * 1 + 1 + 0 = 3`。 为了`B`，它给出零。 输出是`A`。 该算法不会将三分球同时视为两分球和单独的三分球。 最初的两分只是一个方便的底线，额外的一分会将篮子转换为三分。 

第二种情况仅包含罚球：```
A B
0 0
0 0
5 4
```分数是`5`和`4`，所以输出是`A`。 由于罚球不计入篮筐计数，因此必须单独添加。 该算法通过最终的结果完全做到了这一点`+ free_throws`学期。 

第三种情况只有普通的篮子：```
A B
3 2
0 0
0 0
```分数是`6`和`4`，所以输出是`A`。 如果没有三分球，简化的公式就变成了`2 * baskets`，匹配直接解释。 

第四个案例说明了为什么最大的原始篮子数量不一定决定获胜者：```
Left Right
5 6
5 0
0 5
```

`Left`分数`2 * 5 + 5 + 0 = 15`。`Right`分数`2 * 6 + 0 + 5 = 17`，所以正确的输出实际上是：```
Right
```这是一个有用的边界情况，因为它捕获了错误地假设每个三分球应该简单地算作另一个篮子而不调整其值的实现，或者比较篮子计数而不考虑罚球和三分球的实现。 

最后一种情况是大值输入。 例如：```
Alpha Beta
1000000000000000000 999999999999999999
500000000000000000 0
0 1000000000000000000
```无论值的大小如何，该算法都会对每个团队执行相同的三个算术运算。 Python 的整数表示直接处理这些值，因此不需要特殊的溢出逻辑。
