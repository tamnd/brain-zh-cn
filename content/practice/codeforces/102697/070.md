 ## 解决方案
 ## 问题理解

 梅森数的形式为

 [
 M_p = 2^p - 1。 
]

 输入包含指数 (p)，任务是确定 (M_p) 是否实际上是素数。 所需的输出是小写单词`true`当它是素数并且`false`否则。 官方问题特别要求进行 Lucas-Lehmer 素性测试，因为直接构造一个巨大的数字并用普通试除法很快就变得不可行。 该声明还警告中间值可能超过 32 位或 64 位整数，因此需要任意精度算术。 

官方约束没有给出 (p) 的数值上限。 他们明确表示，预期的方法必须在一秒的时间限制和 256 MB 的内存下处理大小可能超过标准机器整数的数字。 在Python中，这意味着我们应该直接使用它的任意精度整数，并避免任何试图枚举(2^p-1)除数的算法。 Lucas-Lehmer 测试执行 (p-2) 次模迭代，并且每个值都保持在 (2^p-1) 以下，因此内存需求与梅森数的大小而不是其数值成正比。 

有几个小情况可能会导致粗心的实施失败。 对于（p=2），数字是（2^2-1=3），它是素数，所以输出为输入`2`是`true`。 一个循环写成`for _ in range(p - 2)`通过执行零迭代自然地处理这个问题，但前提是正确处理初始值。 

对于复合指数，梅森数不能是素数。 例如，输入`4`给出

 [
 2^4-1=15,
 ]

 所以正确的输出是`false`。 盲目地假设每个输入指数都是素数并运行 Lucas-Lehmer 递归的实现可能会违反该定理的前提条件。 

素数指数和梅森素数之间的区别是另一个常见的陷阱。 输入`11`有一个素数指数，但是

 [
 2^{11}-1=2047=23\cdot89,
 ]

 所以正确的输出是`false`。 仅仅测试 (p) 是否是素数是不够的。 

最后，即使最终答案只有一个布尔值，中间序列也可能比 64 位整数大得多。 例如，(p=61) 产生 61 位的梅森数。 C++ 解决方案需要一个大整数库，而 Python 的内置解决方案`int`已经提供了所需的算术。 

## 方法

 最直接的方法是构造(M_p=2^p-1)，然后用普通的素性测试来测试。 试除法是正确的，因为复合整数的除数必须不大于其平方根。 问题在于平方根的大小。 自从

 [
 \sqrt{2^p-1}\approx2^{p/2},
 ]

 最坏的情况需要进行 (2^{p/2}) 次整除性检查。 即使 (p=61) 也已经意味着要检查数十亿个可能除数的规模，所以这种方法是完全不合适的。 

更好的方法来自梅森数的特殊结构。 对于素数指数 (p)，卢卡斯-莱默定理指出，当特定递归以零模 (M_p) 结束时，(M_p=2^p-1) 恰好是素数。 从(s_0=4)开始，反复计算

 [
 s_{i+1}=(s_i^2-2)\bmod M_p。 
]

 恰好经过 (p-2) 次迭代后，当且仅当结果值为零时，(M_p) 才是素数。 官方问题是围绕这个测试明确设计的。 

蛮力方法之所以有效，是因为它试图根据定义建立素数，但它会失败，因为被测试的数字相对于 (p) 具有指数级的多个可能值。 Lucas-Lehmer 观察让我们可以用 (p-2) 模平方来代替巨大的搜索。 该算术仍然对 (p) 位整数执行，但这比检查 (2^{p/2}) 可能的除数要小得多。 

在应用递归之前，我们可以拒绝复合 (p)。 如果 (p) 是合数，则 (2^p-1) 也是合数。 检查 (p) 本身是否为素数的成本仅为 (O(\sqrt p))，与针对大素数指数的 Lucas-Lehmer 工作相比，这可以忽略不计。 特殊情况 (p=2) 会立即被接受。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(2^{p/2})) 整除性检查 | (O(p)) 位 | 太慢了 |
 | 最佳 | (O(p)) 大整数迭代 | (O(p)) 位 | 已接受 |

 (O(p)) 描述对 Lucas-Lehmer 迭代进行计数，并将每个任意精度算术运算视为一个运算。 在位级模型中，成本较高，因为对 (p) 位整数进行平方不是常数时间，但关键的改进是将指数迭代计数替换为线性迭代计数。 

## 算法演练

 1. 读取指数 (p)。 我们只有一个测试用例，因为输入由一个整数组成。 
2. 如果(p=2)，则打印`true`立即地。 相应的梅森数是 (3)，它是素数，卢卡斯-莱默递推通常针对这个最小指数单独定义。 
3. 检查 (p) 是否为素数。 如果是复合的，则打印`false`。 

这种拒绝来自因式分解

 [
 2^{ab}-1=(2^a)^b-1,
 ]

 只要 (p=ab) 就可以被 (2^a-1) 整除。 因此，复合指数永远不能产生素数梅森数。 
4. 将梅森数构造为`m = (1 << p) - 1`。 左移正好产生 (2^p)，减一得到 (2^p-1)。 
5. 初始化 Lucas-Lehmer 状态`s = 4`。 这是定理指定的固定起始值。 
6. 准确重复该循环 (p-2) 次。 在每次迭代中替换`s`与

 [
 (s^2-2)\bmod m。 
]

 求模运算是在平方之后执行的，因此存储的状态永远不需要增长到超出模数本身。 如果没有模运算，中间整数将从一次迭代到下一次迭代爆炸性增长。 
7. 打印`true`如果最终值`s`为零，并且`false`否则。 对于素数指数，卢卡斯-莱默定理使得此零测试对于 (M_p) 为素数来说既是必要的也是充分的。 

为什么它有效：初始化后，变量`s`正是 Lucas-Lehmer 序列模 (M_p) 的对应项。 每次循环迭代都会应用定义下一项的递归，因此在 (p-2) 次迭代之后它包含 (s_{p-2}\bmod M_p)。 卢卡斯-莱默定理指出，对于素数 (p>2)，当 (s_{p-2}=0\pmod{M_p}) 时 (2^p-1) 正是素数。 复合指数已经单独拒绝，直接处理(p=2)。 每个可能的输入都会得到正确的布尔结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_prime(n):
    if n < 2:
        return False
    if n % 2 == 0:
        return n == 2

    d = 3
    while d * d <= n:
        if n % d == 0:
            return False
        d += 2

    return True

def solve():
    p = int(input())

    if p == 2:
        print("true")
        return

    if not is_prime(p):
        print("false")
        return

    m = (1 << p) - 1
    s = 4

    for _ in range(p - 2):
        s = (s * s - 2) % m

    print("true" if s == 0 else "false")

if __name__ == "__main__":
    solve()
```这`is_prime`函数仅适用于指数，不适用于巨大的梅森数。 它检查整除性直到 (\sqrt p)，处理后甚至跳过候选`2`。 

表达式`(1 << p) - 1`优于`2 ** p - 1`这里因为它直接表达了梅森数的二进制结构。 Python 整数具有任意精度，因此即使该值不再适合 64 位，该表达式和随后的平方仍然有效。 

循环运行`p - 2`次，不`p - 1`或者`p - 3`。 Lucas-Lehmer 定理从 (s_0=4) 开始，需要 (s_{p-2})，在恰好 (p-2) 次递归应用后达到。 

表达式`(s * s - 2) % m`必须将模运算保留在循环内。 仅在所有迭代之后进行归约会产生远大于 (M_p) 的数字，从而使实现无法使用。 

Python的任意精度整数也避免了原始语句提到的溢出问题。

import sys
import io

def is_prime(n):
    if n < 2:
        return False
    if n % 2 == 0:
        return n == 2

    d = 3
    while d * d <= n:
        if n % d == 0:
            return False
        d += 2

    return True

def mersenne_prime(p):
    if p == 2:
        return True

    if not is_prime(p):
        return False

    m = (1 << p) - 1
    s = 4

    for _ in range(p - 2):
        s = (s * s - 2) % m

    return s == 0

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    p = int(sys.stdin.readline())
    return "true\n" if mersenne_prime(p) else "false\n"

# Provided samples
assert run("7\n") == "true\n", "sample 1"
assert run("15\n") == "false\n", "sample 2"

# Minimum valid exponent
assert run("2\n") == "true\n", "p = 2"

# Small composite exponent
assert run("4\n") == "false\n", "composite exponent"

# Prime exponent, but not a Mersenne prime
assert run("11\n") == "false\n", "2^11 - 1 is composite"

# Larger known Mersenne-prime exponent
assert run("31\n") == "true\n", "p = 31"

# Larger boundary-style test with a prime exponent that is not a
# Mersenne-prime exponent
assert run("23\n") == "false\n", "2^23 - 1 is composite"

 ## 边缘情况

 对于`2`，输入为：```
2
```该算法输入显式基本情况并打印`true`。 如果没有这种情况，即使定理的迭代形式是针对大于 2 的质数指数规定的，实现也可能会尝试使用一般递推。 

对于复合指数，例如：```
4
```素数检查失败，因为 (4) 可被 (2) 整除。 该算法立即打印`false`，这符合

 [
 2^4-1=15。 
]

 仅检查 Lucas-Lehmer 最终状态而不考虑素数指数条件的粗心实现可能会在其规定的域之外应用定理。 

对于不产生梅森素数的素数指数，请考虑：```
11
```指数通过素性检查。 模数变为

 [
 2^{11}-1=2047。 
]

 然后执行 Lucas-Lehmer 递归 (11-2=9) 次迭代。 它的最终状态是非零模（2047），因此程序打印`false`。 这抓住了返回的常见错误`true`仅仅因为 (p) 是质数。 

对于成功的大型案例：```
31
```指数是质数，模数是

 [
 2^{31}-1=2147483647。 
]

 Lucas-Lehmer 序列在 (29) 次迭代后达到零，因此输出为`true`。 此案例还以超出有符号 32 位整数的大小执行任意精度算术，这与原始声明中提出的问题相匹配。
