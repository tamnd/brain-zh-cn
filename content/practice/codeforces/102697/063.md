 ## 解决方案
 ## 问题理解

 该任务是史瓦西半径公式的直接应用。 给定一个物体的质量 (M)，我们必须使用以下公式计算其事件视界的半径

 [
 r_s=\frac{2GM}{c^2}。 
]

 对于这个问题，常量故意与现实世界的值不同。 我们必须使用 (G=6.67\times10^{-1}=0.667) 和 (c=3\times10^4=30000)。 输入包含一个浮点质量 (M)，值为 (0\le M\le10^9)，输出是相应的浮点半径。 

对 (M) 的约束不会造成任何算法困难，因为答案是通过恒定数量的算术运算获得的。 即使在 (M=10^9) 时，我们也不需要迭代 (M) 的值、构建数组或执行任何搜索。 恒定时间解决方案可以轻松地在一秒限制内并使用恒定内存。 

主要的边缘情况是零质量。 用于输入`0`，公式给出的半径恰好为零，因此正确的输出是`0.0`。 假设质量为正或除以质量的实现在这里可能会失败，即使公式本身没有除以 (M)。```
0
```正确的输出是```
0.0
```另一个常见的错误是使用真实的物理常数而不是问题指定的简化常数。 例如，```
1000000
```必须产生```
0.0014822222222222222
```因为计算使用 (G=0.667) 和 (c=30000)。 使用真实的引力常数和真实的光速会产生完全不同的尺度，这不是所要求的计算。 

最终的边界情况是最大允许质量：```
1000000000
```答案大约是```
1.4822222222222222
```Python 中不存在整数溢出问题，并且与 Python 浮点运算支持的范围相比，中间值很小。 

## 方法

 强力解释将尝试以数值方式获得半径，而不是直接评估给定的方程。 例如，如果质量是整数，则可以通过每单位质量重复添加相同的常数一次来计算与 (M) 成比例的量。 在最大质量下，这将需要 (10^9) 次迭代，这远远超出了一秒竞争性编程解决方案所能承受的范围。 该方法也是不必要的，因为问题已经给出了显式的封闭式表达式。 

暴力法之所以有效，只是因为加法最终可以再现乘法。 当 (M) 变大时它会失败，因为它的运行时间随着输入的数值而不是输入表示的大小而增长。 

关键的观察结果是 (G) 和 (c) 是固定常数。 我们可以将它们组合成一个常数因子：

 [
 r_s=M\cdot\frac{2(0.667)}{30000^2}。 
]

 一旦知道了这个因素，整个问题就是一个浮点乘法。 不涉及隐藏的搜索、模拟、可能半径的迭代或数值方法。 输入只有一个值，因此最优解执行恒定数量的算术运算并立即打印结果。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 重复加法实现中的 O(M) | O(1) | O(1) | 对于 (M=10^9) | 来说太慢了
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取单个浮点值（M）。 将其读取为浮点数是必要的，因为明确允许输入包含十进制值。 
2. 将万有引力常数设置为（G=0.667），将光速设置为（c=30000）。 这些是该问题所需的值，而不是它们的物理值。 
3. 计算（2GM/c^2）。 光速的平方是（30000^2=900000000），所以计算只是一些浮点运算。 
4. 打印结果值。 该问题接受浮点输出，并且样本本身包含许多小数位，因此没有理由手动对结果进行舍入。 

计算背后的不变量很简单：算术表达式求值后，存储的值正是问题指定的数学公式，仅受普通浮点表示形式的影响。 由于除 (M) 之外的每个量都是固定常数，并且不存在迭代决策，因此不存在会偏离预期结果的状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    m = float(input())
    G = 0.667
    c = 30000.0

    radius = 2.0 * G * m / (c * c)
    print(radius)

if __name__ == "__main__":
    solve()
```一线进口`sys`， 和`input`定义为使用`sys.stdin.readline`按要求。 只有一个输入值存在，因此程序只读取一行并将其转换为`float`。 

常量明确写为`0.667`和`30000.0`。 使用`0.667`而不是更精确的 (G) 值才是重要的，因为该陈述故意改变了物理常数。 同样，使用`30000`(c) 是问题定义的一部分。 

表达式`c * c`计算 (c^2)。 直接将公式写为`2.0 * G * m / (c * c)`密切反映了数学定义，并避免了意外使用 (c) 而不是 (c^2) 的任何机会。 

没有循环、数组、递归或特殊的边界检查。 零是自然处理的，因为质量乘以零会产生零半径。 Python 的浮点表示对于所涉及的值的规模来说也绰绰有余。

 ## 边缘情况

 零质量情况直接由公式处理。 有输入```
0
```该算法读取 (M=0)、计算 (2\cdot0.667\cdot0/30000^2=0) 并打印`0.0`。 没有除以 (M)，因此不需要特殊分支。 

最小正质量也锻炼了浮点结果的尺度。 和```
1
```分子是 (1.334)，分母是 (900000000)，大约给出`1.4822222222222223e-09`。 执行整数除法的解决方案会丢失小数结果，这就是计算必须使用浮点运算的原因。 

最大质量```
1000000000
```产生```
1.4822222222222222
```该算法执行与任何较小输入完全相同的操作。 Python中不存在溢出问题，中间分子只有(1.334\times10^9)。 

小数输入情况```
12.5
```确认输入不能被解析`int()`。 正确的计算大约是`1.8527777777777778e-08`。 解析与`float()`保留小数部分，并让同一公式处理整数外观和真正的小数质量。 

最后，使用（G）和（c）的物理值是正确性误差而不是精度改进。 该问题明确定义了 (G=0.667) 和 (c=30000)，因此每个测试都必须使用这些常量进行评估。
