 ## 解决方案
 ## 问题理解

 该问题维护一个状态数据库。 对于每个状态，数据库都会存储其最大允许速度。 构建此数据库后，我们收到多个查询，其中每个查询都命名一个州。 对于每个查询的状态，我们必须打印为该状态存储的速度限制。 

关键的观察结果是查询是独立的。 查询后数据库中没有任何变化，因此唯一的任务是将每个状态名称与其存储的整数有效关联。 

该声明仅给出状态数和查询数为正整数，没有明确的数字上限。 时间限制为 1 秒，内存限制为 256 MB。 这非常有利于总输入大小的线性时间解决方案。 当输入的两个部分都很大时，扫描整个数据库以查找每个查询的方法可能需要二次工作。 哈希表提供预期的恒定时间查找，使总工作量与数据库条目和查询的数量成正比。 

状态名称不包含空格，这意味着每个数据库条目都可以读取为两个空格分隔的标记。 查询的状态名称同样可以作为一个令牌直接读取。 

在某些情况下，粗心的实施可能会失败。 重复的查询必须在不修改数据库的情况下重复回答。 例如，```
2
Texas 85
Hawaii 60
3
Texas
Texas
Hawaii
```产生```
85
85
60
```在回答第一个查询后意外删除状态的实现将在第二个查询上错误地失败`Texas`。 

具有单字符名称的状态也是有效的，因为状态名称只是不带空格的字符串。 例如，```
1
A 50
1
A
```必须产生```
50
```假设状态名称具有特定长度的代码将变得不必要的脆弱。 

如果输入格式允许，数据库还可以包含速度限制为零的状态，并且该值应该像任何其他整数一样存储和打印。 正确的方法并不赋予数值特殊的含义。 

## 方法

 直接暴力方法是将数据库条目存储在数组中。 对于每个查询，从头开始扫描该数组，直到找到请求的状态，然后打印其速度限制。 这是正确的，因为每个数据库条目都显式地将州名称与其速度限制相关联，因此找到匹配的名称即可准确给出所需的答案。 

问题是重复扫描。 如果存在 (S) 数据库条目和 (T) 查询，则查询可以在查找其状态之前检查所有 (S) 条目。 在最坏的情况下，这会执行 (S \times T) 比较。 如果两个值都在 (100000) 左右，则大约是 (10^{10}) 次比较，远远超出 1 秒时间限制所能支持的范围。 

有用的观察是查询键是州名称本身。 我们不需要数据库保持有序，也不需要按范围或数字属性进行搜索。 我们只需要回答“什么值属于这个字符串？”形式的精确相等查询。 哈希表正是为此操作而设计的。 

我们可以将每一对存储为`speed[state] = limit`。 字典建立后，查找状态需要花费预期的 (O(1)) 时间。 读取数据库需要 (O(S))，而回答所有查询则需要 (O(T))。 暴力法和最优方法执行相同的逻辑操作，但字典改变了找到匹配状态的方式。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(ST)) | (O(S)) | 对于大输入来说太慢 |
 | 哈希表| 预期 (O(S + T)) | (O(S)) | 已接受 |

 ## 算法演练

 1. 读取数据库中的状态数（S）。 我们需要这个值只是为了知道后面有多少数据库记录。 
2. 创建一个空字典。 州名称将是键，其速度限制将是关联值，因为以后的每个查询都会为我们提供州名称。 
3. 读取每条(S)数据库记录。 将该行拆分为州名称及其整数速度限制，然后将这对存储在字典中。 在此阶段之后，每个状态都可以直接从其名称中找到。 
4. 读取查询数（T）。 接下来的每一行都包含一个州名称。 
5. 对于每个查询，在字典中查找州名称并将相应的速度限制附加到输出中。 附加答案并将它们一起打印可以避免不必要的重复输出操作。 
6. 打印所有收集到的答案，每行一个。 该顺序与查询顺序完全相同，因为答案是在处理查询时附加的。 

### 为什么它有效

 不变的是，在处理数据库之后，字典包含输入中每个状态的存储速度限制。 当查询命名一个状态时，字典查找会检索与该名称完全关联的值。 由于在回答查询时数据库永远不会被修改，因此重复查询每次都会检索相同的值。 因此，每个打印的数字就是属于查询状态的速度限制。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = int(input())
    speed = {}

    for _ in range(s):
        name, limit = input().split()
        speed[name] = int(limit)

    t = int(input())
    answer = []

    for _ in range(t):
        name = input().strip()
        answer.append(str(speed[name]))

    sys.stdout.write("\n".join(answer))

if __name__ == "__main__":
    solve()
```字典`speed`实现步骤 2 中描述的从州名称到速度限制的映射。数据库循环精确读取 (S) 记录，并将数字字段转换为整数，然后再存储。 

查询循环准确读取 (T) 名称。`strip()`删除每个输入行末尾的换行符，保留用作字典键的状态名称。 由于状态名称不包含空格，`strip()`或者`split()[0]`会在这里工作。 

答案存储为字符串，以便它们可以与换行符连接并一次性写入。 这比打电话更好`print`当查询数量很大时，针对每个查询。 

Python整数不会溢出，因此速度限制值不需要特殊处理。 主要实现细节是将确切的状态名称保留为字典键。 大小写未标准化，因为输入中的状态名称是标识符，而不是不区分大小写的文本。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 预期 (O(S + T)) | 每个数据库条目插入一次，每个查询执行一次预期的恒定时间哈希查找。 |
 | 空间| (O(S)) | 该字典为每个数据库状态存储一个映射。 |

 该解决方案以恒定的次数处理每个输入记录。 即使 (S) 和 (T) 的值非常大，工作量也会随着输入线性增长，而不是两个大小相乘。 这是 1 秒时间限制和 256 MB 内存限制的适当复杂度。

 ## 边缘情况

 由于字典查找是只读的，因此可以自然地处理重复查询的情况。 为了```
2
Texas 85
Hawaii 60
3
Texas
Texas
Hawaii
```第一个`Texas`查找返回`85`，第二个执行相同的查找并再次返回`85`， 和`Hawaii`回报`60`。 最终输出是`85`,`85`,`60`。 查找后不会从字典中删除任何内容。 

最小大小的情况正好有一条数据库记录和一个查询：```
1
A 1
1
A
```该算法插入`A -> 1`，然后立即检索`1`。 输出是`1`。 实现中没有特殊情况，因为单项字典的行为与较大的字典完全相同。 

零速度限制不需要单独处理。 例如，```
2
X 0
Y 50
2
X
Y
```创建映射`X -> 0`和`Y -> 50`，所以输出是```
0
50
```使用`if speed[name]:`而不是直接检索`speed[name]`可能会意外地将零视为缺失，这就是为什么该解决方案只是将存储的值转换为字符串并打印它。 

大数值也可以直接处理。 和```
1
LongState 1000000000
1
LongState
```字典无损地存储整数，输出为`1000000000`。 Python 的整数表示避免了溢出问题。 

最后，大量查询不会与解决方案中的查询数量成比例地增加内存。 字典包含数据库，而答案列表包含输出字符串。 查找本身平均保持恒定时间，因此重复或高度集中的查询不会改变渐近运行时间。
