 ## 解决方案
 ## 问题理解

 我们有一个单淘汰赛，参赛队伍数量为二的幂。 每支球队都有一名种子队，种子队决定固定的分组。 在第一轮中，种子 (s) 对阵种子 (n-s+1)。 然后获胜者晋级到由分组决定的位置，因此爆冷不会改变分组本身，它只会改变哪支球队占据特定位置。 输入还给出了每支球队击败其他球队的概率（以百分比表示）。 

任务是计算每支球队最终赢得整个锦标赛的概率，然后按这些概率的降序打印球队。 概率必须使用其完整精度进行排序，并且在打印时仅四舍五入到最接近的整数。 问题陈述指定 (n) 是 2 的正幂，但已发布的陈述没有给出 (n) 的数字上限。 由于输入已经包含一个（n \times n）概率矩阵，读取输入成本（O（n ^ 2）），因此大大高于二次的算法很快变得不切实际。 预期的动态编程方法使用 (O(n^2 \log n)) 算术运算，这对于锦标赛大小的输入来说很容易管理。 

第一个不明显的情况是只有一支球队的锦标赛。 例如，```
1
Solo
50
```有正确的输出```
Solo 100
```实际上并没有使用自匹配概率 50。 在单队锦标赛中，一支球队会自动获胜，因此将对角线概率视为真正的比赛会给出错误的答案。 

另一种常见的边缘情况是完全对称的锦标赛。 例如，```
4
A B C D
50 50 50 50
50 50 50 50
50 50 50 50
50 50 50 50
```每个团队的正确输出概率为 25。 使用对角线条目作为对手的粗心实现，或者在排序之前对概率进行舍入，可能会扰乱这种对称性。 

第三种边缘情况来自支架布局本身。 有四支球队，第一轮比赛为种子 1 对种子 4 和种子 2 对种子 3。第二轮比赛将是这两场比赛的胜者。 因此，相应的叶顺序是 (1,4,2,3)，而不是 (1,2,3,4)。 如果有八支球队，则顺序变为 (1,8,4,5,2,7,3,6)。 直接使用种子顺序将计算不同锦标赛的概率。 

最后，答案可以恰好在舍入边界上。 如果球队的概率为 (12.5%)，则所需的打印值为 13。排序必须在此舍入之前进行，因为两个接近的概率可以舍入为相同的整数，即使它们的真实顺序不同。 

## 方法

 直接的暴力解决方案可以枚举所有可能的锦标赛结果。 单淘汰赛中有 (n-1) 场比赛，每场比赛都有两个可能的获胜者，因此有 (2^{n-1}) 种可能的完整结果模式。 对于每种模式，我们可以模拟锦标赛，乘以各个游戏结果的概率，并将该概率添加到获胜团队的总数中。 这是正确的，因为游戏获胜者的每个可能序列都是互斥的结果，并且锦标赛冠军的概率恰好是产生该冠军的所有结果的概率之和。 

问题是结果的数量。 枚举所有这些需要 (2^{n-1}) 种情况，如果每种情况都通过所有 (n-1) 场游戏进行模拟，则最坏情况下游戏分辨率操作的数量正好是 ((n-1)2^{n-1})。 即使对于 (n=32)，也已经超过 330 亿次游戏操作。 指数增长使得这种方法无法使用。 

有用的观察是我们实际上并不关心锦标赛的完整历史。 对于特定的分组位置，我们需要知道的是每支球队到达该位置的概率。 一旦知道了这些概率，我们就可以计算出特定球队战胜来自另一半队伍的对手的概率。 

假设一个括号块包含两个较小的块。 令 (p_i) 为团队 (i) 赢得其较小区块的概率。 如果团队 (i) 在左边的区块中，则它赢得组合区块的概率为

 [
 p_i \sum_j p_j P_{i,j},
 ]

 其中 (j) 涵盖右侧区块中的团队，(P_{i,j}) 是 (i) 击败 (j) 的概率。 同样的公式也适用于右侧区域的团队。 

暴力方法之所以有效，是因为它考虑了这些事件的每种可能的组合。 观察到只有每个较小括号的获胜者分布很重要，这让我们可以组合整个子树，而无需枚举它们的内部结果。 我们一次处理一轮比赛，为每支球队保留一个概率。 

首先需要处理一个结构细节。 种子不按照叶子在括号中出现的顺序存储。 我们递归地构建实际的括号顺序。 对于八支球队来说是

 [
 [1,8,4,5,2,7,3,6]。 
]

 一旦球队以这种方式排列，每一轮比赛都对应于组合相邻的区块，这使得动态规划变得简单。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(n2^n)) | (O(n)) | (O(n)) | 太慢了 |
 | 最佳| (O(n^2\log n)) | (O(n^2)) | 已接受 |

 ## 算法演练

1. 阅读球队名称和完整的正面交锋获胜概率矩阵。 将每个矩阵条目从百分比转换为 0 到 1 之间的数字，因此乘法直接表示概率乘法。 
2. 构造锦标赛括号的实际叶序。 对于从(l)到(r)的连续种子区间，递归构造其下半部分的顺序。 使用 (l+r-x) 反映间隔内的每个种子 (x)，然后将原始订单和反映订单交错。 例如，区间 (1\ldots4) 变为 ([1,4,2,3])，(1\ldots8) 变为 ([1,8,4,5,2,7,3,6])。 这准确地反映了所述种子配对如何进入后面的轮次。 
3. 将每支球队赢得当前单队比赛的概率初始化为 1。此时还没有进行任何比赛，因此每支球队都可以确定地到达自己的起始位置。 
4. 处理块大小 (2,4,8,\ldots,n)。 对于当前大小的每个块，将其分成左右两半。 球队 (i) 赢得整个区块的概率等于其赢得自己半场的概率乘以它击败另一半中出现的球队的概率。 
5. 对于左半区的球队 (i)，计算

 [
 新_i = 旧_i
 \sum_{j\in right} old_j P_{i,j}。 
]

 总和是右半场所有可能对手的加权平均值。 对右半场的每支球队进行相同的计算，使用左半场作为可能的对手组。 

1. 用新计算的值替换旧的概率数组，并继续下一个块大小。 当区块大小达到(n)后，每个概率代表相应队伍赢得整个锦标赛的概率。 
2. 按照球队未轮比赛获胜的概率降序对球队进行排序。 在排序过程中保留未舍入的值是必需的，因为该语句明确表示舍入仅在排序后发生。 
3. 将每个概率转换为百分比并将其四舍五入到最接近的整数。 使用`int(probability * 100 + 0.5)`实现非负概率所需的半向上舍入。 打印团队名称，后跟该四舍五入的百分比。 

关键的不变量是在处理块大小（2^k）之后，`dp[pos]`正是团队存储在的概率`order[pos]`赢得成为该 (2^k) 队括号组获胜者所需的每一场比赛。 基本情况是正确的，因为一队获胜的概率为 1。当两个块组合在一起时，另一个块中的每个可能的对手都由其出现的概率表示，乘以相应的头对头概率就得出该完整路径的概率。 总结所有可能的对手，说明球队赢得组合块的每一种相互排斥的方式。 因此，该不变量在每一轮中都保持正确，并且在最后一轮中它给出了所需的冠军概率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def bracket_order(lo, hi):
    if lo == hi:
        return [lo]

    mid = (lo + hi) // 2
    left = bracket_order(lo, mid)

    # Reflect the seeds in the interval.
    right = [lo + hi - x for x in left]

    order = []
    for a, b in zip(left, right):
        order.append(a)
        order.append(b)

    return order

def solve():
    n = int(input())
    names = input().split()

    win = []
    for _ in range(n):
        row = list(map(int, input().split()))
        win.append([x / 100.0 for x in row])

    order = bracket_order(0, n - 1)

    # dp[pos] is the probability that order[pos] wins
    # its current bracket block.
    dp = [1.0] * n

    size = 2
    while size <= n:
        half = size // 2
        new_dp = [0.0] * n

        for start in range(0, n, size):
            middle = start + half
            end = start + size

            for i in range(start, middle):
                team_i = order[i]
                opponent_probability = 0.0

                for j in range(middle, end):
                    team_j = order[j]
                    opponent_probability += (
                        dp[j] * win[team_i][team_j]
                    )

                new_dp[i] = dp[i] * opponent_probability

            for i in range(middle, end):
                team_i = order[i]
                opponent_probability = 0.0

                for j in range(start, middle):
                    team_j = order[j]
                    opponent_probability += (
                        dp[j] * win[team_i][team_j]
                    )

                new_dp[i] = dp[i] * opponent_probability

        dp = new_dp
        size *= 2

    probability = [0.0] * n
    for pos, team in enumerate(order):
        probability[team] = dp[pos]

    teams = list(range(n))
    teams.sort(key=lambda i: (-probability[i], i))

    out = []
    for team in teams:
        rounded = int(probability[team] * 100.0 + 0.5)
        out.append(f"{names[team]} {rounded}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```这`bracket_order`函数仅负责将种子号转换为物理括号位置。 它的递归反射将种子 (s) 播放种子 (n-s+1) 的简单规则转变为后面的每一轮都由相邻块组成的排序。 

这`dp`数组按括号位置而不是团队编号进行索引。 最初，每个条目都是 1，因为每个团队肯定占据自己的一队区块。 在一轮比赛中，`new_dp`使用而不是修改`dp`就位。 这是必要的，因为当前轮中的每个计算都必须使用上一轮的概率。 就地更新会让一个团队看到已经包含当前回合的概率，从而产生不正确的结果。 

该矩阵仍然由原始球队编号索引，因此`order[i]`和`order[j]`每当需要头对头概率时使用。 括号位置和团队标识之间的这种分离可以防止此问题中最常见的索引错误。 

决赛`probability`array 将括号位置概率转换回原始团队编号。 然后排序使用这些精确的浮点值。 次要种子索引只是确定性的平局打破者，并且在概率不同时不会影响所需的排序。 

所有概率都是非负的，所以添加`0.5`在转换为之前`int`执行所需的最接近整数舍入，而无需 Python 的银行家舍入行为。 Python 整数也具有任意精度，因此不存在整数溢出问题。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(n^2\log n)) | 有 (\log_2 n) 轮，每轮总共考虑 (O(n^2)) 组对手对。 |
 | 空间| (O(n^2)) | 概率矩阵使用 (O(n^2)) 空间，而动态编程数组使用 (O(n)) 空间。 |

 (n \times n) 概率矩阵已经需要二次输入空间，因此对于给定的表示来说 (O(n^2)) 存储是不可避免的。 动态规划仅添加线性额外空间。 锦标赛轮次的运行时间以对数因子增长，同时避免了暴力破解的指数 (2^{n-1}) 完整锦标赛结果。

 ## 边缘情况

 对于单人团队的情况，```
1
Solo
50
```

`bracket_order(0, 0)`回报`[0]`。 循环永远不会执行，因为初始块大小已经大于 (n)。 唯一球队的概率仍为 1，因此打印值为 100。对角线值 50 永远不会被解释为实际比赛。 

对于确定性两队情况，```
2
A B
50 100
0 50
```括号顺序是`[A, B]`。 在唯一一轮中，A 之前的概率为 1，击败 B 的概率为 1，因此 A 收到概率 1。B 收到 (1 \times 0 = 0)。 最终输出是`A 100`和`B 0`。 这捕获了意外使用自概率或反转矩阵索引的实现。 

对于对称四队情况，```
4
A B C D
50 50 50 50
50 50 50 50
50 50 50 50
50 50 50 50
```第一轮给每队获胜的概率 (0.5)。 在决赛中，每支球队进入决赛的概率为 (0.5)，然后加权 50% 的机会击败对手，得出 (0.25)。 因此，每个球队都会打印 25。这证实了为球队存储的概率包括其已经需要获胜的每场比赛的不变量。 

对于括号顺序边界，四个种子必须显示为`[1,4,2,3]`， 不是`[1,2,3,4]`。 递归构造首先创建`[1,2]`，将其反映为`[4,3]`，并将它们交错以获得`[1,4,2,3]`。 因此，第一对是种子 1 和 4，完全符合锦标赛规则的要求。 对于八颗种子，相同的结构给出`[1,8,4,5,2,7,3,6]`，因此爆冷会改变占据括号位置的球队，但不会改变晋级下一轮的位置。 

对于64支球队的大型对称情况，每支球队的冠军概率为（1/64），即（1.5625%）。 该算法执行六轮，每次将块大小加倍，并且每个团队的最终概率保持为（1/64）。 由于 (1.5625) 四舍五入为 2，因此每个团队都以概率 2 打印。这会执行每个动态规划回合，并且还确认概率仅在最终排序步骤之后才四舍五入。 

已发布的问题陈述仅将团队数量视为 2 的正幂，没有最大值，因此上面的 64 支团队测试应被视为代表性的大输入，而不是官方声称的最大值。 该算法本身不依赖于特定的 2 的幂，仅依赖于括号结构和（n \times n）概率矩阵。
