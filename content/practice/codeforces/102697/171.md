 ## 解决方案
 ## 问题理解

 给定一个正整数 (n) 和一个整数 (k)。 我们必须打印最接近 (n) 的 (k) 个正回文整数。 排序首先由距 (n) 的绝对距离决定，当两个回文数距离相等时，较小的回文数排在前面。 当数字 (n) 是回文时，则包括数字 (n) 本身，如 (n=6) 的示例所示。 

例如，在 (600) 周围，紧邻其周围的回文是 (595) 和 (606)。 它们的距离是（5）和（6），所以它们是前两个答案。 接下来的下回文和上回文是 (585) 和 (616)，给出距离 (15) 和 (16)。 

已发布的语句指定了一秒的时间限制和 256 MB 的内存，但没有公开当前可用语句中 (n) 和 (k) 的显式上限。 这使得扫描普通整数的解决方案特别没有吸引力。 更重要的是，输出本身包含 (k) 个数字，因此任何解决方案都必须花费至少 (\Omega(k)) 时间来简单地生成答案。 因此，自然目标是 (O(k \log n)) 或 (O(kd))，其中 (d) 是 (n) 的小数位数。 

几种边界情况可能会导致简单的实现失败。 如果(n)本身是回文，则必须先打印它。 用于输入`6 10`，正确的输出开头为`6`， 其次是`5`,`7`,`4`,`8`， 等等。 仅搜索严格小于和严格大于 (n) 的回文的实现将错误地省略`6`。 

下边界也很特殊，因为只允许使用正整数。 用于输入`1 2`，最近的正回文是`1`和`2`。 普通的前身`1`是`0`， 但`0`无法打印。 盲目接受前任的粗心实现将产生无效的答案。 

跨越十的幂是另一个常见的错误来源。 用于输入`99 3`，下一个回文是`101`，不是通过错误镜像不再具有原始长度的前缀而获得的三位数回文。 同样，对于`1000`，前一个回文是`999`，而下一个是`1001`。 

最后，平局必须由较小的数字来解决。 用于输入`10 3`，最接近的回文是`9`和`11`，都在距离 (1) 处，所以`9`必须先打印。 仅基于距离的比较会使输出顺序未指定，并且可能导致判断失败。 

## 方法

 直接的方法是从 (n) 开始，一次向外移动一个整数，并测试每个整数是否为回文。 每当找到回文数时，就会将其添加到答案中，直到收集到 (k) 个回文数。 这是正确的，因为每个正整数都会随着距 (n) 的距离的增加而被检查，并且当距离相等时首先遇到较小的数字。 

问题是回文数很稀疏。 对于 (d) 位数字范围，只有大约 (10^{\lceil d/2\rceil}) 回文，因此搜索可以在找到足够答案之前遍历大量非回文整数。 如果最远的选定回文位于距离 (R) 处，则暴力方法将执行 (\Theta(R)) 回文检查。 检查一个数字的成本为 (O(d))，给出 (\Theta(Rd)) 数字运算。 由于 (R) 不受 (k) 限制，因此这可能比不可避免的 (O(k)) 输出成本大得多。 

关键的观察是，固定数字长度的回文完全由其前半部分决定，包括长度为奇数时的中间数字。 一旦选择了该前缀，剩余的数字将通过反射强制执行。 这意味着我们根本不需要搜索普通整数。 我们可以直接从一个回文跳到上一个或下一个回文。 

对于诸如`753`，取前两位数字，`75`，因为 (\lceil 3/2\rceil=2)。 镜像这个前缀给出`757`，原始前缀处或附近的最小回文。 将前缀减少为`74`给出`747`，并再次减少给出`737`。 增加它给出`767`， 然后`777`，等等。 这些正是周围的回文`753`按数字顺序。 

一旦我们能够获得任意值的直接前驱和后继回文，剩下的任务就变成了双向合并。 在 (n) 下方保留一名候选人，在 (n) 上方保留一名候选人。 在每次迭代中，比较它们与 (n) 的距离。 输出较接近的一个，平局时输出较小的一个。 然后用它的下一个回文替换这一边。 由于每一侧的回文都是按排序顺序生成的，因此这会产生问题所需的全局顺序。

 | 最佳 | (O(kd)) | (O(k+d)) | 已接受 |

 ## 算法演练

 1. 将(n)转换为十进制字符串并确定其长度。 我们使用十进制前缀，因为回文是通过镜像其前半部分来定义的。 
2. 构造回文，通过取 (n) 的前 (\lceil d/2\rceil) 位数字并将它们反映到中心来获得。 这给出了回文，其定义前缀恰好是 (n) 的前缀。 
3. 要找到严格小于值 (x) 的最大回文，首先从 (x) 的前缀构造回文。 如果该回文数已经小于 (x)，则它就是答案。 否则将前缀减一并再次镜像。 减少前缀是对最重要部分的最小可能更改，可以使回文变小。 
4. 要找到严格大于 (x) 的最小回文，请从 (x) 的前缀构造回文。 如果它大于(x)，那就是答案。 否则将前缀加一并镜像它。 这给出了尽可能最小的较大回文。 
5. 将下位候选初始化为(n)的前驱，将上位候选初始化为(n)的后继。 如果 (n) 本身是回文，则先打印它，然后继续这两个严格邻居。 示例显示 (n) 算作所请求的回文之一。 
6. 成对比较较低和较高的候选者`(distance, value)`。 具有较小对的候选者正是下一个需要的候选者，因为距离是主要排序标准，而值是决定因素。 
7. 打印下一个候选后，将其替换为严格位于其下方的下一个回文。 打印上面的候选后，将其替换为严格位于其上方的下一个回文。 重复直到生成 (k) 个回文。 
8. 如果下边达到零，则将其标记为不可用。 零不是有效的输出，因此所有剩余的答案必须来自上侧。 

不变量是在每次迭代之前，`lower`是 (n) 以下最大的尚未打印的正回文，而`upper`是上面 (n) 中最小的尚未打印的回文。 下侧每个未打印的回文不大于`lower`因此不比它更接近 (n)，并且相同的性质对称地成立`upper`。 因此，最接近的剩余回文必须始终是这两个候选者之一。 比较它们`(distance, value)`准确选择所需的下一个答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def make_pal(prefix: int, length: int) -> int:
    s = str(prefix)
    if length % 2 == 0:
        return int(s + s[::-1])
    return int(s + s[-2::-1])

def prev_pal(x: int) -> int:
    s = str(x)
    length = len(s)
    half = (length + 1) // 2
    prefix = int(s[:half])

    p = make_pal(prefix, length)
    if p < x:
        return p

    prefix -= 1

    if prefix == 0:
        return 0

    return make_pal(prefix, length)

def next_pal(x: int) -> int:
    s = str(x)
    length = len(s)
    half = (length + 1) // 2
    prefix = int(s[:half])

    p = make_pal(prefix, length)
    if p > x:
        return p

    prefix += 1

    if prefix == 10 ** half:
        return 10 ** length + 1

    return make_pal(prefix, length)

def solve():
    n, k = map(int, input().split())

    answer = []

    if str(n) == str(n)[::-1]:
        answer.append(n)

    lower = prev_pal(n)
    upper = next_pal(n)

    while len(answer) < k:
        if lower <= 0:
            answer.append(upper)
            upper = next_pal(upper)
            continue

        if upper <= 0:
            answer.append(lower)
            lower = prev_pal(lower)
            continue

        dl = n - lower
        du = upper - n

        if dl <= du:
            answer.append(lower)
            lower = prev_pal(lower)
        else:
            answer.append(upper)
            upper = next_pal(upper)

    sys.stdout.write("\n".join(map(str, answer)))

if __name__ == "__main__":
    solve()
```

`make_pal`是中心建设程序。 对于偶数位数，将反映整个前缀。 对于奇数个数字，最后一个前缀数字是中心，不能重复，所以`s[-2::-1]`反映了中心之前的一切。`prev_pal`首先镜像当前前缀。 如果生成的回文数已经低于`x`，没有更小的变化可以产生更接近的回文。 否则，前缀将递减一次。 如果这使得前缀为零，则不存在低于当前值的相同位数的正回文，因此返回`0`将下侧标记为已耗尽。`next_pal`遵循对称逻辑。 如果增加前缀会创建新的位数，则下一个回文的形式为`100...001`。 例如，之后`999`，增加定义前缀会跨越长度边界并产生`1001`。 

主循环将下部序列和上部序列视为两个排序流。 比较`dl <= du`故意使用`<=`， 不是`<`。 当距离相等时，选择较低的候选者实现了问题中较​​小的回文数在前的要求。 

Python 整数具有任意精度，因此实现不存在固定宽度溢出问题。 唯一可能昂贵的操作是转换和镜像十进制前缀，其成本与位数成正比。
