 ## 解决方案
 ## 问题理解

 任务是判断给定的字符串是否是“警报字符串”。 当字符恰好存在时，字符串就具有此属性`a`其中出现了三次。 所有其他字符（包括输入中出现的空格）都是无关的。 所需的输出是`YES`当计数正好为三并且`NO`否则。 官方问题页面确认输入是单个字符串，并且令人震惊的字符串恰好包含三个`a`人物。 

问题页面上规定的字符串长度没有数字限制，因此安全的解释是解决方案应该与输入量呈线性关系。 二次算法会重复检查相同的字符，并且随着字符串的增长而变得不必要的昂贵。 单遍需要每个字符一次操作，这是一秒 256 MB 问题的自然目标。 官方存档给出了一秒的时间限制和256 MB的内存限制。 

可能导致实现错误的主要输入细节是字符串可能包含空格。 阅读与`input().split()`会丢弃空格，更严重的是，只会读第一个单词。 例如，输入`an apple actually appeared`包含四个`a`字符并且必须产生`NO`，如官方示例所示。 

另一个边缘情况是恰好出现了 3 次，无论它们出现在何处。 为了`aardvark`， 这`a`字符出现在前两个位置和最后一个位置，所以答案是`YES`。 意外检查连续三个的解决方案`a`字符会错误地拒绝它。 

包含超过 3 次出现的字符串也必须被拒绝。 例如，`aaaa`有四个`a`字符，所以它的输出是`NO`。 一个粗心的解决方案，只检查字符串是否至少包含三个`a`字符会被错误打印`YES`。 

最后，产生的次数必须少于 3 次`NO`。 例如，`abc`不包含`a`，所以答案是`NO`。 错误地初始化其计数器或检查是否存在的代码`a`在这种情况下，如果不进行计数，它就会失败。 

## 方法

 最直接的暴力方法是考虑每个发生位置并计算`a`通过再次扫描整个字符串来获取字符。 这是正确的，因为每次完整扫描都会给出准确的数量`a`字符，但它执行了不必要的重复工作。 如果字符串有长度`n`，对其每个进行全面扫描`n`职位执行准确`n^2`最坏情况下的字符检查。 即使我们只执行三次扫描，工作量仍然是所需量的三倍。 

蛮力方法之所以有效，是因为我们关心的属性仅取决于`a`人物。 关键的观察是，在读取一次字符串时可以累积该总数。 当我们遇到一个`a`，我们增加一个计数器。 其他所有字符都使计数器保持不变。 在最后一个字符之后，计数器恰好是`a`原始字符串中的字符。 

这将问题转化为简单的线性扫描。 不需要频率字典，因为只有一个字符重要，并且读取字符串后无需存储该字符串。 蟒蛇的`count('a')`也直接执行所需的线性扫描，但显式循环使底层算法变得清晰，并避免了有关如何处理输入的任何歧义。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将整个输入行作为字符串读取，保留空格。 使用`input().rstrip('\n')`仅删除行结尾并保留字符串的每个字符可供检查。 
2. 将计数器初始化为零。 计数器代表的数量`a`目前为止看到的角色。 
3. 从左到右扫描字符串。 每当当前字符是`a`，将计数器加一。 没有其他字符影响答案，因为定义仅取决于出现的情况`a`。 
4. 扫描完成后，将计数器与 3 进行比较。 打印`YES`如果等于三，则打印`NO`否则。 检查相等性而不是`>= 3`是必要的，因为出现四次或以上并不令人担忧。 

为什么它有效：处理完字符串的任何前缀后，计数器恰好等于字符串的数量`a`该前缀中的字符。 最初，前缀为空且计数器为零，因此该属性成立。 当下一个字符不是时`a`，两者的实际数量`a`字符和计数器保持不变。 当它是`a`，两者都增加一。 因此，在整个扫描过程中，不变量保持不变。 处理完整个字符串后，计数器正好是字符串的总数`a`字符，所以打印`YES`当它等于三时正好符合定义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().rstrip('\n')

count_a = 0

for ch in s:
    if ch == 'a':
        count_a += 1

print("YES" if count_a == 3 else "NO")
```第一行读取完整的输入行。`rstrip('\n')`被用来代替`strip()`因为`strip()`删除字符串两端的空格，而空格是输入中的有效字符，不应更改。 问题示例明确包含包含空格的字符串。 

循环直接实现计数步骤。 没有边界算术、索引或子字符串构造，因此没有需要管理的差一位置。 计数器仅针对确切的字符递增`a`。 

最后的条件故意使用`count_a == 3`。 一个条件，例如`count_a >= 3`会接受包含四个或更多的字符串`a`字符，这违反了定义。 

对于可能的计数器值，Python 整数不会溢出，因此不需要特殊的数字处理。

## 测试用例```python
import sys
import io

def solve():
    input = sys.stdin.readline
    s = input().rstrip('\n')
    count_a = 0

    for ch in s:
        if ch == 'a':
            count_a += 1

    print("YES" if count_a == 3 else "NO")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("coderams competition number eleven\n") == "NO\n", "sample 1"
assert run("aardvark\n") == "YES\n", "sample 2"
assert run("an apple actually appeared\n") == "NO\n", "sample 3"

# Minimum-size input
assert run("a\n") == "NO\n", "fewer than three a characters"

# Exactly three, all adjacent
assert run("aaa\n") == "YES\n", "exactly three adjacent a characters"

# More than three
assert run("aaaa\n") == "NO\n", "more than three a characters"

# Three occurrences separated by spaces and other letters
assert run("a b a c a\n") == "YES\n", "spaces and separated occurrences"

# No a characters
assert run("bcdef\n") == "NO\n", "no a characters"

# Large input, exactly three a characters
large = "b" * 100000 + "a" + "b" * 100000 + "a" + "b" * 100000 + "a\n"
assert run(large) == "YES\n", "large boundary-sized input"

 ## 边缘情况

 第一个微妙的情况是包含空格的输入。 为了`an apple actually appeared`，该算法读取整行而不是将其拆分为单词。 它遇到了四个`a`字符，所以`count_a`以四结束，输出为`NO`。 一个不小心`input().split()[0]`实施只会检查`an`并可能产生错误的计数。 官方问题包括这个确切的样本。 

第二种情况恰好是不连续出现的三次。 有输入`aardvark`，计数器演变为`0 -> 1 -> 2 -> 2 -> 2 -> 2 -> 3 -> 3 -> 3`，所以最终的结果是`YES`。 该算法没有对邻接做出任何假设，这与定义相符。 

第三种情况出现次数超过3次。 有输入`aaaa`，计数器变为`1`， 然后`2`， 然后`3`， 然后`4`。 最终的对比是`4 == 3`，这是假的，所以输出是`NO`。 这捕获了测试计数是否已达到至少三的常见错误。 

第四种情况出现次数少于3次。 有输入`aa`，计数器结束于 2，输出为`NO`。 当算法看到第一个或第二个时，它不会过早地接受`a`，因为它只有在处理完完整的字符串后才会做出决定。 

第五种情况是大输入，其中三个相关字符相距很远。 包含 100,000 的字符串`b`字符，那么`a`, 另外 100,000`b`人物，另一个`a`, 另外 100,000`b`人物，以及最后的结局`a`仍然生产`YES`。 扫描对每个字符执行一次恒定时间检查，因此其运行时间随输入大小而不是随三个出现位置之间的距离线性增长。
