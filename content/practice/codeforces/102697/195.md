 ## 解决方案
 ## 问题理解

 地牢是一个 (n \times n) 网格。 一个点代表一个可行走的单元格，而`X`代表一堵墙。 玩家从左上角的单元格开始，可以在四个基本方向上一次移动一个单元格。 任务是计算有多少个可步行单元属于与起始单元相同的连接区域。 不允许对角移动，不能跨越网格外的墙壁和位置。 官方声明给出的时间限制为1秒，内存限制为256MB，但没有提供(n)的数字上限。 

缺少数字界限的关键后果是算法应该随着单元格的数量进行缩放，而不是在网格上执行重复的工作。 网格本身包含 (n^2) 个字符，因此仅读取输入就需要 (O(n^2)) 时间。 因此，(O(n^2)) 遍历是自然目标。 随着 (n) 的增长，(O(n^3)) 或 (O(n^4)) 方法会出现问题，尤其是在一秒限制下。 

在一些边缘情况下，粗心的实施可能会失败。 如果网格是单个可行走单元，例如```
1
.
```答案是`1`。 仅计算移动后到达的单元格的实现可能会错误地返回`0`。 

例如，如果起始单元格被墙壁包围```
3
.X.
XXX
...
```唯一可访问的单元格是起始单元格，所以答案是`1`。 遍历必须在寻找其邻居之前计算起始位置。 

一个地区也可以通过多种途径触及自身。 例如，```
3
...
...
...
```有答案`9`。 如果粗心搜索没有将单元格标记为已访问，则可能会重复进入同一循环，并且对单元格进行多次计数或永远不会终止。 

最后，地牢其他地方的墙壁不会影响答案，除非它们将起始组件分开。 为了```
3
..X
XXX
...
```答案是`2`，因为只有左上角组件中的两个单元格是可到达的。 计算网格中的每个点将错误地返回`5`。 

## 方法

 直接的暴力方法可以重复扫描整个网格，以从已知可访问的单元中找到可访问的单元。 例如，在发现一个新单元格后，我们可以检查所有 (n^2) 个位置，以查看该单元格是否应导致另一个位置变得可到达。 在最坏的情况下，可能有 (n^2) 个发现，每个发现都可能触发完整的 (n^2) 个单元扫描，从而进行 (n^4) 个网格检查。 对于 (n=1000)，最多需要 (10^{12}) 次检查，远远超出一秒程序可以处理的范围。 

暴力方法之所以有效，是因为可达性是可传递的：一旦单元格可达，每个相邻的可步行单元格也变得可达。 问题在于，通过扫描不相关的单元来反复重新发现这一事实会浪费几乎所有的计算。 

有用的观察是，这正是网格上的连通分量问题。 每个可行走单元都是一个图顶点，当它们的单元共享一条边时，两个顶点之间存在一条边。 我们只需要包含 ((0,0)) 的连通分量。 广度优先搜索或深度优先搜索访问每个可达单元一次并检查其四个可能的邻居。 由于每个单元格都被处理一次，因此总工作量与网格中单元格的数量成正比。 

访问过的标记是必不可少的。 如果没有它，一对相邻的可步行单元可以不断地将搜索发送回彼此。 我们可以通过将每个发现的点更改为来避免单独访问的数组`X`。 由于这些单元永远不需要再次处理，因此改变网格可以产生相同的效果，同时使用更少的辅助内存。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 重复全格扫描| (O(n^4)) | (O(n^2)) | 太慢了 |
 | BFS 或 DFS 洪水填充 | (O(n^2)) | (O(n^2)) | 已接受 |

 ## 算法演练

 1. 阅读 (n \times n) 个地下城并检查起始单元格。 如果是墙，则没有可行走的起始组件，所以答案是`0`。 最初的问题将起始位置描述为地牢中的一个空间，但处理这种情况使得实现更加稳健。 
2. 将起始单元放入堆栈中，并将其标记为立即访问。 我们使用堆栈进行迭代深度优先搜索，这避免了Python的递归深度限制。 
3. 当堆栈不为空时，删除一个单元格并将答案加一。 单元在被移除时被计数，因为放入堆栈中的每个单元都已被确认为新的可达单元。 
4. 检查四个相邻位置。 对于每个邻居，首先检查其行和列是否在网格内。 然后检查是否是一个点。 如果是，则将其更改为`X`并将其压入堆栈。 

在推动邻居之前对其进行标记是故意的。 假设两个已经发现的细胞都接触同一个新细胞。 第一个标记并推动它，所以第二个会看到`X`并且无法再次推动它。 
5. 当堆栈变空时，从起始位置可到达的每个单元都已被访问。 打印已处理单元格的数量。 

### 为什么它有效

 不变的是，当前堆栈中的每个单元以及已处理的每个单元都属于起始单元的连通分量，并且每个单元一经发现就被标记。 当算法从已处理的单元移动到可步行的邻居时，该邻居通过这条附加边所遵循的现有路径连接到起始组件，因此添加它是正确的。 相反，任何可到达的单元格都必须有一条从起点开始的路径。 沿着该路径一次一个边缘，搜索最终会发现路径上的每个可步行单元格，除非它之前已经发现过。 因此，堆栈最终包含并处理每个可到达的单元一次，而墙壁和断开的区域永远不会被计算在内。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n = int(input())
    grid = [bytearray(input().strip(), "ascii") for _ in range(n)]

    if grid[0][0] != ord('.'):
        print(0)
        return

    stack = [(0, 0)]
    grid[0][0] = ord('X')
    answer = 0

    directions = ((1, 0), (-1, 0), (0, 1), (0, -1))

    while stack:
        r, c = stack.pop()
        answer += 1

        for dr, dc in directions:
            nr = r + dr
            nc = c + dc

            if 0 <= nr < n and 0 <= nc < n and grid[nr][nc] == ord('.'):
                grid[nr][nc] = ord('X')
                stack.append((nr, nc))

    print(answer)

if __name__ == "__main__":
    solve()
```网格存储为`bytearray`行，以便可以直接更改发现的单元格`.`到`X`。 这消除了对第二个（n \times n）布尔访问矩阵的需要。 

堆栈包含等待处理的坐标。 起始单元在进入堆栈之前而不是在弹出时进行标记，因为在插入时进行标记可以防止重复条目。 

四个方向对分别代表下、上、右、左。 边界条件使用`0 <= nr < n`和`0 <= nc < n`，它准确地描述了有效的网格坐标，并避免了负索引和超出最后一行或列的访问。 

没有递归，所以即使非常大的连通分量也不能溢出Python的递归限制。 Python 整数也具有任意精度，尽管答案最多为 (n^2)，因此普通整数溢出无论如何都不会成为问题。 

进口的`deque`此实现实际上并不需要，因为 Python 列表对于堆栈来说就足够了。 将堆栈保留为列表可以提高效率 (O(1))`append`和`pop`操作从最后开始。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(n^2)) | 每个 (n^2) 个单元被读取一次，并且每个可到达的单元恰好检查四个方向。 |
 | 空间| (O(n^2)) | 网格占用 (O(n^2)) 空间，并且 DFS 堆栈在最坏情况下可以包含 (O(n^2)) 坐标。 |

 (O(n^2)) 运行时间是渐近最优的，因为输入本身包含 (n^2) 个单元并且必须读取。 该问题指定了 1 秒的时间限制和 256 MB 的内存，因此避免重复的全网格扫描是主要要求。

 ## 边缘情况

 对于单人牢房地牢```
1
.
```算法标记`(0,0)`在开始搜索并将其放入堆栈之前。 它被弹出一次，所以`answer`变成`1`。 所有四个候选邻居均未通过边界检查。 堆栈变空，输出为`1`。 

对于分离的起始细胞，```
3
.X.
XXX
...
```算法过程`(0,0)`并检查它的四个邻居。 右边和下面的位置是墙，而另外两个位置是在网格之外。 没有新的单元格被推送，因此搜索立即结束并给出答案`1`。 下排是无关紧要的，因为墙壁从一开始就将其断开。 

对于完全开放的网格，```
3
...
...
...
```每个被发现的细胞都可能导致另一个未被发现的邻居。 每个单元格在被压入时都会被标记，因此即使许多单元格之间有多条路径，也不会出现单元格两次进入堆栈的情况。 所有九个细胞最终都被处理，给出`9`。 

对于断开连接的情况```
4
..XX
..XX
XXXX
....
```前两行形成四个单元的组成部分，而底行形成四个单元的另一个组成部分。 开始于`(0,0)`，搜索可达`(0,1)`,`(1,0)`， 和`(1,1)`，但是每条通往底行的路线都会遇到`X`。 答案是`4`， 不是`8`。 

大型全点测试练习整个网格是一个连通组件的情况。 对于（1000 × 1000）网格，该算法恰好处理一百万个单元并检查每个单元的四个方向。 不进行递归调用，并且每个单元格在发现时立即被标记，因此遍历在输入大小上保持线性。
