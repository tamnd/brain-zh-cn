 ## 解决方案
 ## 问题理解

 Ken Ken 棋盘是一个 (n \times n) 拉丁方。 每个单元格接收从 (1) 到 (n) 的值，每行只包含每个值一次，每列也执行相同的操作。 附加结构是连接的笼子的集合。 笼子要么将单个单元格固定为给定值，要么要求其单元格中的值使用加法或乘法达到目标。 减法和分裂笼总是恰好包含两个细胞。 对于减法，绝对差必须等于目标。 对于除法，较大的值除以较小的值必须等于目标。 笼子本身不需要不同的值。 

输入将笼边界描述为 ASCII 绘图。 电路板尺寸在 4 到 7 之间，因此最多有 49 个单元。 官方限制为 15 秒和 256 MB，这为我们提供了比典型的两秒竞赛问题更多的空间，但对所有单元分配进行盲目搜索仍然没有希望。 

(n \le 7) 的关键结果是每个单独的单元格最多有七个可能的值。 这使得位掩码成为行和列限制的自然表示，而小域也使得精确的笼可行性检查变得便宜。 我们应该在搜索深入之前使用笼算术来切断分支，而不是首先生成任意拉丁方。 

第一个解析边缘情况是一个笼子可以跨越多个单元，因此线索不一定存在于每个单元中。 例如，第一个样本包含一个笼子，其第一行看起来像`|40x        |2-     |`，意味着`40x`笼子占据了几个单元。 假设每个单元都有自己的线索的解析器将创建完全不同的笼子并产生错误的板。 该样本的正确输出是`25431`,`12345`,`34512`,`41253`,`53124`。 

第二种边缘情况是减法和除法是无序的。 笼子有标记`2-`接受 3 和 1 等任意顺序的值，而`2/`接受 4 和 2 的任意顺序。 仅检查`a - b == target`或者`a / b == target`默默地拒绝有效的解决方案。 第二个示例包含两个操作并具有输出`34251`,`53412`,`15324`,`42135`,`21543`。 

第三种边缘情况是单细胞笼。 一条线索，例如`2`不是等待另一个单元格的算术目标。 它将该单元精确地固定为 2。将其视为单单元和或乘积恰好可以在数值上起作用，但将空线索视为零，或要求每个笼子都包含一个运算符，则会破坏解析器。 

第四个边缘情况是笼连接性和行或列连接性之间的区别。 仅当水平或垂直方向上没有墙壁时，两个细胞才属于同一个笼子。 对角接触不连接保持架。 基于实际墙壁的洪水填充比尝试从线索串的位置推断笼子更安全。 

## 方法

 最直接的暴力解决方案将 (n) 个值之一分配给每个 (n^2) 个单元格。 在搜索树的叶子上，它检查每一行、每一列和每个笼子。 这是正确的，因为最终会考虑每个可能的棋盘，因此唯一的有效棋盘必须出现在搜索中的某个位置。 问题在于搜索空间。 在最大的情况下，可以有 (7^{49})，大约 (2.6 \times 10^{41})，完整的作业。 即使在恒定时间内检查一项作业也是完全不可行的。 

同一想法的更好版本在搜索过程中保留行和列约束。 如果一行已包含 1、3 和 5，则无需在该行中再次尝试这些值。 我们可以用七位掩码来表示使用的值，因此查找单元格中可用的值就变成了几个位操作。 

剩下的弱点是，行和列修剪单独使用算术笼，直到为时已晚。 考虑一个目标为 6 的三单元格加法笼。如果其当前总和已经是 5 并且还剩下一个单元格，则只有值 1 可以工作。 如果当前总和为 6 并且还剩下两个单元格，则不可能立即进行分支。 类似的推理也适用于乘积，尽管乘法需要多加小心。 

关键的观察结果是，可以在不知道其未分配单元的最终值的情况下测试部分笼。 对于加法，如果剩余 (k) 个单元格，则它们的贡献必须位于 (k) 和 (kn) 之间。 对于乘法，剩余目标必须恰好是 (1) 到 (n) 中 (k) 个数字的乘积。 由于目标是固定的，因此我们可以通过使用 (1) 到 (n) 中的值递归分解剩余目标并进行记忆来准确检查这一点。 

减法和除法就更简单了。 它们恰好有两个单元格，因此一旦知道一个值，我们就可以尝试另一个单元格的最多七种可能性。 

在理论上最坏的情况下，所得的求解器仍然是回溯算法。 Ken Ken 求解并不会仅仅因为我们使用了巧妙的修剪就神奇地变成了多项式。 实际的改进来自于使几乎所有错误的部分电路板都尽早失效，并选择具有最少当前可用值的下一个单元。 这是约束满足问题的标准最小剩余值思想。 

暴力破解之所以有效，是因为最终会检查每个可能的分配，但会失败，因为它的树有 (n^{n^2}) 个叶子。 行、列和笼子都可以拒绝部分分配的观察结果让我们只搜索该树中仍然可以得出解决方案的一小部分。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(n^{n^2})) | (O(n^2)) | 太慢了 |
 | 使用 MRV 和笼修剪进行回溯 | (O(n^{n^2})) 最坏情况 | (O(n^2 + C)) | 已接受 |

 这里(C)是笼子的总数，即(n^2)。 第二种方法具有相同的最坏情况指数界限，但对于问题所使用的 4 x 7 谜题，约束使得实际搜索量大大减小。 该声明还表示，测试谜题来自一本书，并且可能是人类可以解决的，这是约束驱动搜索是适当的一个强有力的实际迹象。 

## 算法演练

1. 读取 ASCII 板，同时保留其几何形状。 单元格的宽度为四个字符，因此紧邻 (c) 列之后的垂直墙位于位置 (4c+4)。 (r) 行下方的水平墙占据了第 (2r+2) 行上属于该单元格的四个字符位置。 
2. 使用开放的墙壁淹没牢房以恢复笼子。 从每个未访问的单元格开始，当分隔符是空格时访问其右邻居，当水平分隔符包含空格时访问其下邻居。 为每个到达的单元分配相同的笼子标识符。 这使用实际绘图，而不是对笼子形状进行假设。 
3. 对于每个笼子，按行优先顺序检查其单元格。 第一个非空单元格包含目标和操作，因为该问题保证线索位于最上面的单元格中，当出现平局时选择最左边的单元格。 仅包含数字的线索代表一个固定的单细胞笼。 否则将最终字符解析为`+`,`x`,`-`， 或者`/`。 
4. 为每一行和每一列创建一个位掩码。 位(v-1)表示值(v)是否已被使用。 单元格最初可以接收其行掩码和列掩码中都缺少该位的每个值。 
5. 立即放置所有单细胞笼。 这些是固定值，而不是搜索决策。 放置每个值时更新相应的行和列掩码。 
6. 在尝试候选值之前，检查其笼子是否仍能达到目标。 对于加法笼，计算当前总和以及未分配单元格的数量。 如果目标位于区间之外`sum + remaining`到`sum + remaining * n`，分支是不可能的。 对于乘法笼，将目标除以当前乘积，并询问商是否可以精确地表示为乘积`remaining`值从 1 到 (n)。 
7. 对于减法和除法笼，枚举其两个单元格的可能值。 当绝对差等于目标值时，减法对有效。 当较大值能被较小值整除并且它们的商等于目标值时，除法对有效。 枚举很小，因为 (n \le 7)。 
8. 在所有未分配的单元格中，选择通过行、列和笼检查的值数量最少的单元格。 这是最小剩余值规则。 如果一个单元格只有一个可能值，而另一个单元格有五个可能值，则在第一个单元格上进行分支更有可能立即暴露矛盾。 
9. 按升序尝试剩余值。 放置值，更新其行和列掩码，然后递归。 如果递归调用成功，则保留分配。 如果失败，请在尝试下一个候选之前撤消分配和掩码。 
10. 当没有未分配的单元格时，每一行和每一列都已经是不同的，并且每个笼子在每次分配后都经过检查。 因此，完成的板是一个有效的 Ken Ken 解决方案。 

不变的是，搜索维护的每个部分板都满足行和列的独特性约束，并且每个笼子在算术上仍然是可实现的。 仅当没有完成可以满足这些约束之一时，才丢弃候选者。 因此删除分支并不能删除有效的解决方案。 相反，当棋盘已满时，所有约束都已被准确检查，因此返回的棋盘有效。 

## Python 解决方案```python
import sys
import re
from functools import lru_cache

input = sys.stdin.readline
sys.setrecursionlimit(100000)

def solve(data: str) -> str:
    lines = data.splitlines()
    n = int(lines[0])

    board_lines = lines[1:2 * n + 2]
    width = 4 * n + 1
    board_lines = [line.ljust(width) for line in board_lines]

    # Find cages by flood filling through open walls.
    cage_id = [[-1] * n for _ in range(n)]
    cages = []

    for sr in range(n):
        for sc in range(n):
            if cage_id[sr][sc] != -1:
                continue

            cid = len(cages)
            cells = []
            stack = [(sr, sc)]
            cage_id[sr][sc] = cid

            while stack:
                r, c = stack.pop()
                cells.append((r, c))

                # Move right if there is no vertical wall.
                if c + 1 < n:
                    if board_lines[2 * r + 1][4 * c + 4] == ' ':
                        if cage_id[r][c + 1] == -1:
                            cage_id[r][c + 1] = cid
                            stack.append((r, c + 1))

                # Move down if there is no horizontal wall.
                if r + 1 < n:
                    segment = board_lines[2 * r + 2][4 * c + 1:4 * c + 5]
                    if all(ch == ' ' for ch in segment):
                        if cage_id[r + 1][c] == -1:
                            cage_id[r + 1][c] = cid
                            stack.append((r + 1, c))

            cages.append(cells)

    # Parse the clue belonging to each cage.
    cage_target = []
    cage_op = []

    for cells in cages:
        clue = None
        for r, c in sorted(cells):
            text = board_lines[2 * r + 1][4 * c + 1:4 * c + 5].strip()
            if text:
                clue = text
                break

        m = re.fullmatch(r'(\d+)([+\-/x])?', clue)
        target = int(m.group(1))
        op = m.group(2)

        cage_target.append(target)
        cage_op.append(op)

    board = [[0] * n for _ in range(n)]
    row_mask = [0] * n
    col_mask = [0] * n

    # Place all fixed single-cell cages.
    for cid, cells in enumerate(cages):
        if len(cells) == 1:
            r, c = cells[0]
            value = cage_target[cid]
            bit = 1 << (value - 1)

            if (row_mask[r] & bit) or (col_mask[c] & bit):
                return ""

            board[r][c] = value
            row_mask[r] |= bit
            col_mask[c] |= bit

    @lru_cache(maxsize=None)
    def product_can(cid, count, value):
        """
        Can 'value' be represented as a product of exactly 'count'
        integers from 1 through n?
        """
        if count == 0:
            return value == 1

        if value < 1:
            return False

        for x in range(1, n + 1):
            if value % x == 0:
                if product_can(cid, count - 1, value // x):
                    return True

        return False

    def cage_possible(cid, extra_r=-1, extra_c=-1, extra_value=0):
        """
        Check whether a cage can still reach its target.

        The optional extra assignment is used while evaluating a candidate
        without modifying the board.
        """
        cells = cages[cid]
        target = cage_target[cid]
        op = cage_op[cid]

        values = []
        for r, c in cells:
            if r == extra_r and c == extra_c:
                values.append(extra_value)
            else:
                values.append(board[r][c])

        if op is None:
            return values[0] == target if values[0] else target >= 1

        if op == '+':
            current = 0
            remaining = 0

            for v in values:
                if v:
                    current += v
                else:
                    remaining += 1

            return (
                current + remaining <= target
                and target <= current + remaining * n
            )

        if op == 'x':
            current = 1
            remaining = 0

            for v in values:
                if v:
                    current *= v
                else:
                    remaining += 1

            if current > target or target % current != 0:
                return False

            needed = target // current
            return product_can(cid, remaining, needed)

        # Subtraction and division cages contain exactly two cells.
        a, b = values

        if a == 0 and b == 0:
            for x in range(1, n + 1):
                for y in range(1, n + 1):
                    if op == '-' and abs(x - y) == target:
                        return True
                    if op == '/' and max(x, y) % min(x, y) == 0:
                        if max(x, y) // min(x, y) == target:
                            return True
            return False

        if a == 0:
            for x in range(1, n + 1):
                if op == '-' and abs(x - b) == target:
                    return True
                if op == '/' and max(x, b) % min(x, b) == 0:
                    if max(x, b) // min(x, b) == target:
                        return True
            return False

        if b == 0:
            for y in range(1, n + 1):
                if op == '-' and abs(a - y) == target:
                    return True
                if op == '/' and max(a, y) % min(a, y) == 0:
                    if max(a, y) // min(a, y) == target:
                        return True
            return False

        if op == '-':
            return abs(a - b) == target

        if min(a, b) == 0:
            return False

        return max(a, b) % min(a, b) == 0 and max(a, b) // min(a, b) == target

    def candidates(r, c):
        used = row_mask[r] | col_mask[c]
        cid = cage_id[r][c]

        result = []
        for value in range(1, n + 1):
            bit = 1 << (value - 1)
            if used & bit:
                continue

            if cage_possible(cid, r, c, value):
                result.append(value)

        return result

    def search():
        best_r = -1
        best_c = -1
        best_values = None

        for r in range(n):
            for c in range(n):
                if board[r][c] != 0:
                    continue

                vals = candidates(r, c)

                if not vals:
                    return False

                if best_values is None or len(vals) < len(best_values):
                    best_r = r
                    best_c = c
                    best_values = vals

                    if len(vals) == 1:
                        break
            if best_values is not None and len(best_values) == 1:
                break

        if best_values is None:
            return True

        cid = cage_id[best_r][best_c]

        for value in best_values:
            bit = 1 << (value - 1)

            board[best_r][best_c] = value
            row_mask[best_r] |= bit
            col_mask[best_c] |= bit

            if cage_possible(cid) and search():
                return True

            board[best_r][best_c] = 0
            row_mask[best_r] ^= bit
            col_mask[best_c] ^= bit

        return False

    if not search():
        return ""

    return '\n'.join(''.join(map(str, row)) for row in board)

def main():
    data = sys.stdin.read()
    sys.stdout.write(solve(data))

if __name__ == "__main__":
    main()
```实现的第一部分从墙壁而不是从线索位置重建笼子。 输入交替单元格内容线和水平边界线，而每个单元格占据四个字符位置。 即使输入表示不保留尾随空格，填充每行也可以使墙访问安全。 

行和列掩码使用位 (v-1) 作为值 (v)。 由于 (n) 最多为 7，因此掩码适合单个小整数。 测试一个值是否可用只是`used & bit`，添加或删除它是按位或或异或。 

这`cage_possible`function 是中心修剪例程。 加法仅需要下限和上限，因为每个剩余单元格都可以独立地取 1 到 (n) 之间的任何值。 对于乘法，简单的数字区间太弱了，所以`product_can`准确检查目标。 它的记忆是由笼子、剩余细胞数量和剩余产物决定的。 

减法和除法代码故意使用`abs`和`max / min`。 这符合这样的事实：操作是根据较大和较小的值定义的，而不是根据它们在笼内的物理顺序来定义的。 显式整除性测试完全避免了浮点运算。 

MRV 搜索不会永久维护候选集。 它从当前的行、列和笼状态重新计算它们，这使回溯变得简单，并避免了恢复复杂的域更改。 仅在选择候选者后才设置棋盘值，并且当候选者失败时，相应的掩码位将立即删除。 

最终输出将每一行连接起来，没有空格。 这与提供的格式匹配，因为每个值都是 (n \le 7) 的单个数字。 原始语句将输出描述为每行 (n) 个整数，并且其示例连续显示这些一位数值。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(n^{n^2})) 最坏情况 | 理论上，回溯可以尝试每个单元中的每个值，并进行额外的小笼子检查 |
 | 空间| (O(n^2)) 加上记忆 | 棋盘、掩码、笼数据、递归堆栈和缓存的产品状态都受小棋盘 | 的限制。 

理论界限仍然是指数的，但 (n) 最多为 7，并且谜题实例是结构化的 Ken Ken 谜题，而不是任意的拉丁方完成实例。 MRV 规则、行和列掩码、精确的加法界限、精确的产品可行性以及立即的两单元笼检查可以尽早消除无效分支。 15 秒的限制为这种约束驱动的搜索提供了足够的实际空间来满足预期的实例。

 ## 边缘情况

 在洪水填充解析阶段处理仅在第一个单元中具有线索的多单元笼。 对于输入片段`|40x        |2-     |`，第二壁之前的四个单元被放入一个笼子中，只有第一个单元贡献`40x`线索。 其他单元格具有空文本，并且不被视为单独的笼子。 这再现了第一个样品所需的笼结构。 

减法笼如`3-`接受值为 1 和 4 的原因是`abs(1 - 4) == 3`。 如果求解器仅计算`1 - 4`，它将拒绝有效的对。 该实现检查绝对差异，因此两个物理顺序是等效的。 

划分笼如`2/`值 2 和 4 被接受，因为`max(2, 4) // min(2, 4) == 2`。 首先执行整除性检查，因此诸如 2 和 3 这样的对被拒绝，而不是被视为浮点商。 

对于单细胞笼，例如`2`，单元格立即被分配。 如果该值已出现在同一行或同一列中，则输入将不一致并且求解器会拒绝它。 在有效的竞赛谜题中，这种情况不会发生，但显式检查可以防止内部掩码变得不一致。 

处理大型乘法笼时无需枚举每个可能的元组。 假设四个单元格必须乘以 24。一旦当前乘积为 6，则剩余目标为 4，并且还剩下两个单元格。 已记下的`product_can`函数询问 4 是否可以写为从 1 到 (n) 的两个值的乘积，当这些值可用于笼时，通过 (1 \times 4) 或 (2 \times 2) 成功。 这种精确的算术修剪比仅仅检查当前产品是否低于目标要强大得多。 

最后，一个单元格可能没有与其行和列兼容的值，即使它的笼子在算术上看起来仍然是可能的。 MRV 扫描立即检测到空候选集并回溯。 这是防止搜索徘徊在笼式算术永远无法挽救的部分拉丁方中的关键机制。
