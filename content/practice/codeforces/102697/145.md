 ## 解决方案
 ## 问题理解

 该任务是一个基数转换问题。 第一个外来物种使用基数 (a) 写入整数，而第二个外来物种使用基数 (b)。 我们得到了两个基数和一个使用基数 (a) 中有效数字书写的数字 (n)。 我们必须打印以 (b) 为基数的相同整数。 

例如，对于输入基数 (7)，数字`63642`代表

 [
 6\cdot7^4+3\cdot7^3+6\cdot7^2+4\cdot7+2。 
]

 输出基数为 (9)，因此该表达式的十进制值必须使用 (9) 的幂表示，产生`23550`。 官方说法给出了(a,b\le 10)，所以每个数字都可以直接用字符表示`0`通过`9`。 该问题有 1 秒时间限制和 256 MB 内存限制。 当前语句中没有明确说明位数上限，因此算法的自然参数是输入长度 (L)。 解决方案应避免重复重新计算位置幂的算法，因为它们的工作量随 (L) 呈二次方增长。 

有几种边界情况很容易处理不当。 单个零是可能的最小数值。 例如，`2 10`其次是`0`必须产生`0`。 重复除该值并构建数字的转换例程可能会意外地生成一个表示零的空字符串。 

如果输入表示形式允许，也可以出现前导零。 例如，`2 10`和`000101`代表相同的值`101`，即`5`，所以输出必须是`5`， 不是`000101`或空结果。 

源基数和目标基数可以相同。 例如，`10 10`和`123456`必须产生`123456`。 通过中间整数进行正确的转换可以自动处理这个问题。 

输出可以包含比输入更多的数字。 例如，`2 10`使用足够长的二进制数可以产生可比或更大文本长度的十进制数。 实现不得假设输出与输入具有相同的长度。 

## 方法

 一种直接的方法是使用其位置能力独立评估每个源数字。 如果数字有 (L) 位，我们可以将每一项计算为 (d_i a^{L-1-i})，其中幂是通过重复乘以 (a) 获得的。 该方法在数学上是正确的，因为位置符号正是这些项的总和。 然而，从头开始计算幂执行

 [
 (L-1)+(L-2)+\cdots+1=\frac{L(L-1)}2
 ]

 最坏情况下的乘法仅用于源转换。 这项工作是 (O(L^2))，这是不必要的。 

关键的观察是位置符号可以增量评估。 假设目前看到的数字代表一个值（x）。 当下一个数字是 (d) 时，将该数字附加到基数 (a) 中会将值更改为

 [
 x\c点a+d。 
]

 没有理由重新计算任何幂。 从零开始，对每个数字应用一次递归，可以在 (O(L)) 算术步骤中转换整个源表示形式。 

一旦知道了整数值，就可以从相反的操作中得到目标表示。 将整数 (x) 除以 (b) 得到商和余数，

 [
 x=q\cdot b+r,
 ]

 其中 (r) 正是最低有效基数 (b) 数字。 对 (q) 重复此操作将从右到左提取剩余的数字。 将收集到的余数反转即可得到所需的表示。 

这提供了干净的两阶段解决方案。 蛮力之所以有效，是因为位置表示法是数字加权幂的总和，但当这些幂被重复重新计算时就会失败。 霍纳式评估消除了重复，而重复除法给出了新基数中的规范表示。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(L^2)) 算术步骤 | (O(L)) | 对于大输入来说太慢 |
 | 最佳 | (O(L)) 位置步长，加上输出转换 | (O(L)) | 已接受 |

 复杂性表示法将累加整数的算术视为一次操作，这是此初等转换问题的标准模型。 对于 Python 的任意精度整数，实际的位复杂度还取决于该整数的大小。 

## 算法演练

 1. 读取源基址 (a)、目标基址 (b) 和数字字符串 (n)。 该字符串最初必须保持为字符串，因为它的字符是源表示形式的各个数字。 
2. 将累计整数值设置为零。 对于源字符串中的每个字符，将其转换为其数字 (d)，然后使用更新值`value = value * a + d`。 这是位置递归，所以在处理任何前缀之后，`value`正是该前缀表示的整数。 
3. 如果累计值为零，则打印`0`立即地。 否则，即使正确的表示形式包含一个零数字，重复除法也不会产生余数。 
4. 当该值为正数时，将其除以目标基数 (b)。 将余数附加到数字列表并用商替换该值。 每个余数都是下一个目标数字，从最低有效数字开始。 
5. 将收集到的数字反转并转换为字符。 除法过程会向后发现数字，因此反转会恢复其正常的从最高有效到最低有效的顺序。 
6. 打印结果字符串。 由于两个基数最多为 10，因此每个数字都由相应的十进制字符表示。 

第一阶段背后的不变性是，在处理前（k）个源数字之后，累积值恰好等于基数（a）中这（k）个数字所表示的整数。 附加一位数字精确地应用了位置规则 (x\mapsto xa+d)，因此不变式在每次迭代中都存在。 

对于第二阶段，每次除法之后我们有 (x=q b+r)，因此 (r) 被迫成为 (x) 的最低有效基数 (b) 数字。 商包含所有剩余的高位数字。 重复这个论证证明收集到的余数正是相反顺序的目标表示。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())
    s = input().strip()

    # Convert from base a to an ordinary Python integer.
    value = 0
    for ch in s:
        digit = ord(ch) - ord('0')
        value = value * a + digit

    # Zero needs a special representation.
    if value == 0:
        print(0)
        return

    # Convert the integer to base b.
    digits = []
    while value > 0:
        value, remainder = divmod(value, b)
        digits.append(chr(ord('0') + remainder))

    print(''.join(reversed(digits)))

if __name__ == "__main__":
    solve()
```第一个循环实现算法演练步骤 2 中的递归。使用`ord(ch) - ord('0')`使数字转换明确并避免依赖库基础解析器。 

累计的`value`是Python整数，因此不存在固定宽度溢出。 这很重要，因为该语句没有给出位数的小上限，并且有效输入可以表示比 64 位值大得多的整数。`divmod(value, b)`在一次运算中执行步骤 4 所需的商和余数运算。 余数总是在`0`和`b - 1`，因此它是有效的目标数字。 

零检查是必要的，因为循环`while value > 0`将为值零执行零次。 如果没有检查，程序将打印一个空行而不是`0`。 

逆转也是必要的。 例如，转换十进制`13`到基地`2`产生余数`1`， 然后`0`， 然后`1`。 这些被发现为`1, 0, 1`从最不重要到最重要，在本例中恰好是回文。 为了`10`，余数为`0, 1`，并将它们反转给出正确的表示`10`。

 ## 边缘情况

 零情况是重复除法实现中最常见的无声故障。 考虑：```
2 10
0
```Horner 阶段计算`value = 0`。 除法循环无法运行，因为它的条件是`value > 0`，因此如果没有专门的零检查，输出将为空。 该实现检测到零并准确打印`0`。 

前导零不会改变所表示的整数。 为了：```
2 10
000101
```累计值是`0, 0, 0, 1, 2, 5`。 然后目标转换除以`5`除以10，求余数`5`，并打印`5`。 前导零永远不会影响数学值，因为将零乘以源基数仍然会得到零。 

相同的源基地和目标基地不需要特殊的分支。 和：```
10 10
111111
```第一阶段获得整数（111111）。 第二阶段以 10 为基数表示相同的整数，产生`111111`。 这是一个有用的检查，可以检查两个转换阶段是否独立正确。 

输出较长的边界情况是：```
2 10
11111111
```源值变为 (255)。 除以 10 次提取`5`， 然后`5`， 然后`2`，因此反转余数会产生`255`。 该算法从不假设输入和输出具有相同的位数。 

最后，碱基本身可以位于允许范围的两端。 例如：```
9 2
888888
```来源评估对待每一个`8`作为有效的以 9 为基数的数字。 然后将所得整数重复除以 2，生成二进制表示形式`1001001010101001000`。 数字转换保持正确，因为每个支持的基数最多为 10，因此字符`0`通过`9`足以表示每个可能的数字。
