 ## 解决方案
 ## 问题理解

 该问题给出了一个单词词典和几个数字串。 编码仅使用六个字母：`o`变成`0`,`i`变成`1`,`e`变成`3`,`a`变成`4`,`s`变成`5`， 和`t`变成`7`。 每隔一个字母都会有一个空白，因此当我们只查看结果数字序列时，它就会消失。 

例如，`hasty`包含相关字母`a`,`s`， 和`t`，所以就变成了`457`。 这个词`funtastuc`包含`u`,`n`， 和`c`，消失，留下`t`,`a`,`s`,`t`， 或者`7457`。 任务是找到每个字典单词，其编码形式正是所请求的数字字符串。 字典已经按字母顺序排序，因此匹配的单词必须以相同的顺序打印。 

官方声明指定了 1 秒的时间限制和 256 MB 的内存限制，但没有公布字典大小、字长或查询数量的数字上限。 这一省略使得预期的复杂性特别重要。 由于可能存在许多字典单词和许多查询，因此扫描整个字典以查找每个查询是不安全的。 我们应该对每个字典单词处理一次，并使以后的每个查询都直接查找。 

在几种简单的情况下，实现可能会悄无声息地出错。 首先，六个映射字母之外的字母必须被忽略，而不是被视为数字。 对于输入```
1
hasty
1
457
```输出是```
1
hasty
```要求单词的每个字符都有映射的解决方案会错误地拒绝`hasty`由于`h`和`y`。 

其次，不同的单词可以有相同的编码。 例如，```
3
a
ba
ca
1
4
```产生```
3
a
ba
ca
```因为这三个词都简化为`4`。 为每个编码字符串仅保留一个单词将丢失有效答案。 

第三，消失的字母可能出现在映射的字母之间。 为了```
2
taste
tasty
1
7457
```正确的输出是```
2
taste
tasty
```这两个词都减少为`7457`。 将数字字符串与原始单词中的连续字符进行比较的解决方案将会失败，因为未映射的字母会消失。 

最后，查询可能没有匹配的字典单词。 为了```
2
a
hello
1
57
```正确的输出很简单```
0
```没有匹配的单词，因此计数后没有单词行。 

## 方法

 直接的方法是独立处理每个查询。 对于一个查询，扫描每个字典单词，将其字符转换为数字，同时忽略未映射的字符，并将结果字符串与查询进行比较。 这是正确的，因为比较完全模拟了编码规则。 

假设有`D`字典单词，每个单词最多有长度`L`，并且有`T`查询。 在最坏的情况下，暴力方法检查`D * L`每个查询的字符，给出`T * D * L`字符检查只是为了构建编码。 比较生成的编码可以添加另一个`O(TDL)`在最坏的情况下工作。 当输入变大时，对每个查询重复此工作是使该方法不适合的部分。 

暴力方法之所以有效，是因为每个单词都可以根据请求的数字独立进行测试。 问题是字典在查询之间不会改变，因此重新计算相同的编码是浪费工作。 

关键的观察是每个字典单词都有一个编码的数字字符串。 我们可以在读取字典时计算该字符串一次，并将其用作哈希表中的键。 与键关联的值是具有该编码的字典单词列表。 

例如，对样本字典进行处理后，key`7457`商店`funtastuc`,`tasty`， 和`untasty`。 查询`7457`那么只需要查字典而不是检查所有八个单词。 

由于原始字典已按字母顺序排序，因此将每个单词附加到其编码键的列表中会自动保留所需的输出顺序。 预处理后无需排序。 

由此产生的方法是：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(TDL)`加上比较|`O(1)`额外，不包括输入 | 对于大输入来说太慢 |
 | 最佳 |`O(S + Q + R)`预计|`O(S + D + R)`| 已接受 |

 这里`S`是字典中的字符总数，`Q`是所有查询字符串的总长度，并且`R`是打印的匹配单词总数。 预期的`O(1)`哈希表查找应用于每个查询。 

## 算法演练

 1. 创建从六个相关字母到其数字的映射：`o -> 0`,`i -> 1`,`e -> 3`,`a -> 4`,`s -> 5`， 和`t -> 7`。 任何其他字符都将被忽略，因为它代表编码形式中的空白。 
2. 创建一个哈希表，其键是编码的数字字符串，其值是原始字典单词列表。 这会将所有成为相同数字的单词组合在一起。 
3. 按照给定的顺序阅读每个词典单词。 通过访问每个字符并仅当该字符出现在映射中时才附加数字来构建其编码形式。 然后将原始单词附加到属于该编码形式的列表中。 

字典已经按字母顺序排序，因此按输入顺序插入单词也会使每个存储的列表按字母顺序排序。 
4. 读取每个查询数字字符串并将其直接用作哈希表键。 如果该键存在，则其存储的列表恰好包含匹配的字典单词。 如果不存在，则查询有零个匹配项。 
5. 打印所选列表中的单词数，然后打印单词本身。 对于不存在的密钥，仅打印`0`。 

### 为什么它有效

 不变的是，在处理字典的任何前缀之后，每个处理过的单词都准确地存储在通过将问题的编码规则应用于该单词而获得的字符串下。 未映射的字母永远不会出现在该键中，而每个映射的字母都以其规定的数字和原始顺序出现。 因此，在处理整个字典后，存储在查询字符串下的列表包含编码等于该查询的每个字典单词，并且不包含编码不同的单词。 由于单词是按字母字典顺序插入的，因此每个列表都已按所需的输出顺序排列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    d = int(input())

    mapping = {
        'o': '0',
        'i': '1',
        'e': '3',
        'a': '4',
        's': '5',
        't': '7',
    }

    encoded_words = {}

    for _ in range(d):
        word = input().strip()
        code = ''.join(mapping[c] for c in word if c in mapping)
        encoded_words.setdefault(code, []).append(word)

    t = int(input())
    out = []

    for _ in range(t):
        query = input().strip()
        matches = encoded_words.get(query, [])

        out.append(str(len(matches)))
        out.extend(matches)

    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```这`mapping`字典准确地表示了语句中的六种转换。 在字典预处理期间，生成器表达式扫描每个字符一次。 条件`c in mapping`删除变成空白的字符，同时`mapping[c]`提供相应的数字。`setdefault(code, [])`第一次遇到编码时创建一个新列表，然后将后面的单词附加到同一列表中。 这是必要的，因为几个不同的字典单词可能具有相同的编码。 

字典是按字母顺序阅读的，因此列表不需要额外的`sort()`。 之后对每个组进行排序会增加不必要的工作，并且会掩盖输入顺序已经提供所需排序的事实。 

对于每个查询，`get(query, [])`如果编码存在则给出匹配列表，否则给出空列表。 输出累积在`out`并在最后写一次，这避免了许多个人的开销`print`来电。 

Python 整数不参与编码，因此不存在溢出问题。 数字序列故意保留为字符串，如果存在此类查询，它也会保留前导零。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O(S + Q + R)`预计| 每个字典字符被编码一次，每个查询被查找一次，并且每个打印的匹配单词都有助于`R`。 |
 | 空间|`O(S + D + R)`| Encoded keys, original dictionary words, and stored match lists occupy space proportional to the input and retained output associations. |

 The official time limit is one second and the memory limit is 256 MB, while the published statement does not provide numerical bounds for`D`，字长，或`T`。 最佳解决方案避免将字典大小乘以查询数量，这是大输入所需的关键改进。

## 边缘情况

 考虑输入```

```

 现在考虑```

```

ba
ca
```这解决了每个编码值仅存储一个字的常见错误。

1

```该算法从不尝试将查询与每个原始字符对齐。 It compares only the filtered encoding.
