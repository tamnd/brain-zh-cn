 ## 解决方案
 ## 问题理解

 我们需要计算构成毕达哥拉斯三元组并且还满足附加方程的整数三元组 (a,b,c)。 边的顺序为 1≤a≤b≤c≤n，因此 c 是斜边。 除了通常的毕达哥拉斯方程外

 a 2 +b 2 =c 2 ，

 三元组还必须满足 Vasya 的错误公式

 c=a 2 -b。 

对于每个测试用例，输入是单个上限 n。 我们需要输出有多少个三元组满足这两个方程，同时所有三个边长最多为 n。 官方给出的约束是1≤t≤10 4 和1≤n≤10 9，时间限制为2秒，内存限制为256 MB。 

n 的值足够大，以至于检查直到 n 的每个可能的边长将过于昂贵。 对于一个最大尺寸的测试用例，即使是 O( n ​ ) 循环也大约需要 44722 次迭代，而对 10 4 个测试用例独立执行该操作可能会接近 4.5×10 8 次迭代。 这两个方程的有用结构使我们能够将整个测试用例减少到恒定数量的整数运算。 

在一些小情况下，直接公式可能会出错。 对于 n=1，没有有效的三角形，所以答案是`0`。 仅计算 a 的奇数值而不要求 a≥3 的公式可能会错误地计算 a=1，从而得出 b=0。 

对于 n=3，答案也是`0`。 虽然a=3是奇数候选，但对应的值为b=4和c=5，因此斜边已经超过n。 

当 n=5 时，答案是`1`，对应于(3,4,5)。 诸如 c<n 而不是 c≤n 之类的边界条件会错误地拒绝该三元组。 

## 方法

 一种简单的方法是尝试所有可能的 a、b 和 c，检查两个方程。 这是正确的，因为每个有效答案都经过明确检查，但它需要 O(n 3 ) 组合。 当n=10 9 时，大约有10 27 个组合，这是完全不可行的。 

我们已经可以通过观察一旦 a 固定，两个方程就确定 b 和 c 来改进这一点。 开始于

 a 2 +b 2 =c 2

 代入 c=a 2 −b，我们得到

 a 2 +b 2 =(a 2 -b) 2 。 

展开右侧可得

 a 2 +b 2 =a 4 -2a 2 b+b 2 。 

取消 b 2 并除以 a 2，这是有效的，因为 a 是正数：

 1=a 2 -2b。 

因此

 b= 2 a 2 −1 ​ ,

 并使用 c=a 2 −b，

 c= 2 a 2 +1 ​ 。 

这立即解释了为什么 a 一定是奇数。 更重要的是，每个可能的三元组现在都由单个整数 a 确定。 

我们也知道

 c= 2 a 2 +1 ​ ≤n，

 所以

 a 2 ≤2n−1。 

因此a最多可以是

 L=⌊ 2n−1 ​ ⌋。 

订购条件又增加了一项限制。 对于a=1，该公式给出b=0，这是无效的。 对于每个奇数 a≥3，我们有 a≤b≤c。 因此，a 的有效值恰好是从 3 到 L 的奇数整数。 

我们甚至可以直接对这些值进行计数，而不用循环遍历这些值。 从 1 到 L 的奇数个数为 ⌊(L+1)/2⌋。 删除a=1片叶子

 ⌊ 2 L+1 ​ ⌋−1=⌊ 2 L−1 ​ ⌋.

 因此，每个测试用例都可以使用精确的整数平方根在 O(1) 时间内求解。

 ## 算法演练

 1. 读取 n 并计算

 L=⌊ 2n−1 ​ ⌋。 

L值是a的最大可能值，因为c=(a 2 +1)/2不能超过n。 

1. 统计满足3≤a≤L的奇数a。 

计数是

 ⌊ 2 L−1 ​ ⌋.

 每一个这样的奇数 a 都恰好产生一个有效的三元组，因此不需要构造或单独测试相应的 b 和 c。 

1. 打印该计数。 

直接计数公式也可以处理较小的 n。 当n=1时，L=1，结果为零。 当n=2时，L=1。 当n=5时，L=3，正好给出一个三元组。 

### 为什么它有效

 两个必需的方程将每个有效的三元组强制转换为以下形式

 (a, 2 a 2 −1 ​ , 2 a 2 +1 ​ )。 

因此，有效三元组与斜边至多为n的奇数a≥3之间存在一一对应关系。 斜边条件恰好是 a 2 ≤2n−1，因此对 a 的那些奇数值进行计数时，每个有效三元组恰好计数一次，并且不能包括无效三元组。 

## Python 解决方案```python
Pythonimport sysinput = sys.stdin.readline

def solve():    t = int(input())
    for _ in range(t):        n = int(input())
        # c = (a^2 + 1) / 2 <= n        # so a^2 <= 2n - 1.        limit = (2 * n - 1) ** 0.5        limit = int(limit)
        # Correct possible floating-point rounding using integer adjustment.        while (limit + 1) * (limit + 1) <= 2 * n - 1:            limit += 1        while limit * limit > 2 * n - 1:            limit -= 1
        # Valid a are odd integers in [3, limit].        answer = (limit - 1) // 2        print(answer)

if __name__ == "__main__":    solve()
```推导意味着实现只需要最大的可行a。 该代码首先计算 2n−1 的整数值，然后计算从 3 开始的奇数值。 

即使初始估计使用浮点，校正循环也使平方根计算准确。 当n≤10 9 时，开平方的值至多为2⋅10 9 -1，因此校正最多需要微小的恒定量的工作。 Python 的整数运算也避免了溢出。 

表达式`(limit - 1) // 2`是奇数 3,5,7,... 的计数，最多`limit`。 使用`limit + 1`或者从 1 开始计数会引入无效的 a=1 情况。 

更简单的实现可以使用`math.isqrt`，这在 Python 中更可取，因为它直接计算精确的整数平方根：```python
Pythonimport sysfrom math import isqrt
input = sys.stdin.readline

def solve():    t = int(input())
    for _ in range(t):        n = int(input())        limit = isqrt(2 * n - 1)        print((limit - 1) // 2)

if __name__ == "__main__":    solve()
```这是推荐版本。

 ## 边缘情况

 对于 n=1，输入为`1`该算法计算出 L=⌊ 1 ​ ⌋=1。 表达式`(1 - 1) // 2`给出`0`。 这正确地拒绝了形式代数候选 a=1，因为它会产生 b=0，这不是正边长。 

对于 n=3，输入为`3`。 我们得到 L=⌊ 5 ​ ⌋=2，因此在要求的范围 3≤a≤2 内不存在奇数 a。 答案是`0`。 仅检查 a 是否为奇数的粗心实现可能会错误地认为 a=1。 

对于 n=5，输入为`5`。 这里L=⌊ 9 ​ ⌋=3，所以算a=3。 它产生 b=4 和 c=5，并且因为条件是 c≤n，所以三元组有效。 答案是`1`。 

对于n=12，最大可能的a为4，因此仅计算a=3。 三元组 (5,12,13)​​ 不包括在内，因为它的斜边是 13>12。 这捕获了使用 b 而不是 c 来限制 a 的常见错误，因为 c 是最大边并且是实际的限制量。 

对于最大输入 n=10 9，我们有

 L=⌊ 1999999999 ​ ⌋=44721。 

有效值都是从 3 到 44721 的奇数，即

 2 44721−1 ​ =22360。 

该算法无需枚举这 22360 个值即可达到此结果，这特别有用，因为最多可以有 10 4 个测试用例。
