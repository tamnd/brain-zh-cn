 ## 解决方案
 ## 问题理解

 我们得到了一个歌曲播放列表。 每首歌都有一个标题和时长，写为`MM:SS`，其中分钟和秒使用两位数。 任务是打印最长歌曲的标题。 如果几首歌曲的持续时间完全相同，则输入中最早出现的歌曲必须获胜。 

一旦转换为单个单位，持续时间就很容易比较。 一首经久不衰的歌`06:13`持续`6 * 60 + 13 = 373`秒，同时`05:57`持续`357`秒。 比较结果整数比比较原始字符串更简单且不易出错。 

官方声明并未明确歌曲数量的上限。 时间限制为一秒，内存限制为256 MB。 由于可以通过检查每首歌曲一次来找到所需的答案，因此`O(n)`scan 是自然目标，仅使用恒定的额外空间。 二次算法的性能约为`n(n-1)/2`成对比较，随着播放列表的增长，这会变得不必要的昂贵。 

在某些情况下，粗心的实施可能会默默地选择错误的歌曲。 首先，领带必须保留较早的歌曲。 例如：```
3
First 10:00
Second 10:00
Third 09:59
```正确的输出是`First`。 当新的持续时间相等时替换当前答案的实现将错误地打印`Second`。 

其次，比较必须考虑分钟和秒。 例如：```
2
Short 09:59
Long 10:00
```正确的输出是`Long`。 将持续时间错误地视为普通十进制数可能会导致无效比较。 

最后，第一首歌曲最长时必须正确处理：```
2
OnlyGoodOne 12:00
Smaller 11:59
```正确的输出是`OnlyGoodOne`。 将最佳持续时间初始化为零对于有效的正持续时间有效，但将最佳标题初始化为任意后续歌曲可能会引入可避免的特殊情况。 

## 方法

 直接的暴力解决方案可以将每首歌曲与其他歌曲进行比较，保留较长的一首。 这是正确的，因为在考虑了所有配对之后，每首歌曲都已与所有可能的竞争对手进行了比较。 然而，它多次重复相同的信息。 为了`n`歌曲，有`n(n-1)/2`无序对，因此最坏情况下的比较次数是`n(n-1)/2`，即`O(n²)`。 

蛮力方法之所以有效，是因为比较两个持续时间是常数时间，但它会失败，因为最长的歌曲不需要分别与每首歌曲进行比较。 从左到右扫描播放列表时，我们可以保留迄今为止看到的最好的歌曲。 当下一首歌曲更长时，它就成为新的最佳歌曲。 当它相等或更短时，没有任何变化。 

关键的观察是在处理第一个之后`i`歌曲，我们只需要关于它们的一条信息：这些歌曲中最长的持续时间，以及具有该持续时间的最早的标题。 后来的每一个决定都只取决于这个总结，而不是之前的每首歌曲。 这将问题减少到一次通过输入。 

平局规则自然决定了比较运算符。 仅当新的持续时间严格大于当前的最佳持续时间时，我们才会更新。 如果持续时间相等，则保留现有答案将保留播放列表中较早的位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) 或 O(1) | 对于大 n 来说太慢 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取歌曲数量。 我们将每首歌曲处理一次，因此无需存储整个播放列表。 
2. 对于每首歌曲，将输入行分为标题和持续时间。 标题是第一个以空格分隔的标记，而持续时间是给定输入格式下的第二个标记。 
3. 转换持续时间`MM:SS`变成几秒钟。 如果分钟数是`m`秒是`s`，总持续时间为`60 * m + s`。 使用一个整数可以让我们进行精确而直接的比较。 
4. 保留代表迄今为止最好的歌曲的两个变量：标题和持续时间。 对于第一首歌曲，直接从其数据初始化这些变量。 这避免了依赖可能不适用于每个可能的输入的人为持续时间。 
5. 对于后续的每首歌曲，将其持续时间与当前最佳持续时间进行比较。 仅当新的持续时间严格大于时才替换存储的标题和持续时间。 平局被故意忽略，因为当前歌曲是较早遇到的。 
6. 处理完所有歌曲后，打印存储的标题。 此时它代表整个输入中最长的歌曲，当持续时间相等时选择最早出现的歌曲。 

不变量是在处理完播放列表的任意前缀后，`best_time`是该前缀的最大持续时间，`best_title`是其第一次出现的标题。 较短的歌曲不能改变最大值，相同的歌曲不能取代第一次出现。 严格较长的歌曲成为已处理前缀中唯一的最佳持续时间。 由于不变量在每个输入行之后都成立，因此它在最后一行之后成立，从而使存储的标题恰好成为所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    best_title = None
    best_time = -1

    for _ in range(n):
        title, duration = input().split()

        minutes, seconds = map(int, duration.split(':'))
        total_seconds = minutes * 60 + seconds

        if total_seconds > best_time:
            best_time = total_seconds
            best_title = title

    print(best_title)

if __name__ == "__main__":
    solve()
```该循环一次读取一首歌曲，并立即将其持续时间转换为秒。 没有理由保留不再是答案候选的歌曲，因此输入将作为流进行处理。 

条件使用`>`而不是`>=`。 这是平局规则的核心实现细节。 和`>`，一首相同时长的歌曲不会影响现有答案，因此具有该时长的第一首歌曲仍保持选中状态。 

分割持续时间`:`给出两个十进制整数. 转换`minutes * 60 + seconds`避免依赖于字符串如何按字典顺序进行比较，并且适用于每个有效的`MM:SS`期间。 

Python 整数不会溢出，尽管实际的持续时间字段足够小，普通的固定宽度整数类型也足够了。 

初始化`best_time = -1`意味着第一首有效歌曲始终成为初始候选歌曲。 由于问题至少包含一首歌曲，`best_title`保证在决赛前分配`print`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每首歌曲都被读取、解析和比较一次 |
 | 空间| O(1) | O(1) | 仅存储当前最佳标题和持续时间 |

 该解决方案很容易满足一秒的时间限制，因为它对每首歌曲执行恒定的工作量。 无论播放列表中有多少歌曲，它都会保持在 256 MB 内存限制内，因为永远不会存储完整的播放列表。

## 边缘情况

 对于单首歌曲播放列表，输入为：```
1
Solo 00:01
```该算法开始于`best_time = -1`。 唯一一首有时长的歌曲`1`， 所以`1 > -1`状态变成`best_title = Solo`,`best_time = 1`。 没有进行任何其他处理，输出是`Solo`。 因此，即使输入大小尽可能小，初始化也是有效的。 

对于相同的持续时间，请考虑：```
3
First 10:00
Second 10:00
Third 09:59
```第一首歌曲将最佳时长设置为`600`。 第二首歌也有时长`600`， 但`600 > 600`为 false，因此状态保持不变。 第三首歌有时长`599`，所以它也被忽略。 输出是`First`，完全匹配所需的最早出现规则。 

对于分钟边界，请考虑：```
2
AlmostTen 09:59
ExactlyTen 10:00
```第一个持续时间变为`9 * 60 + 59 = 599`。 第二个变成`10 * 60 + 0 = 600`，它更大，所以答案变为`ExactlyTen`。 因此，输出为：```
ExactlyTen
```这捕获了处理`MM:SS`文本作为普通的十进制表示形式。 

对于大型播放列表，算法永远不需要重新访问较早的歌曲。 每行贡献一次持续时间转换和最多一次更新。 即使有 100000 首歌曲，主循环迭代的数量仍然恰好是 100000 次，而成对暴力比较将需要大约 50 亿对检查。 单遍不变量使解决方案能够干净地扩展。
