 ## 解决方案
 ## 问题理解

 RGB 颜色会出现此问题。 颜色由三个整数表示，`R`,`G`， 和`B`，每一个之间`0`和`255`。 我们得到一个这样的三元组，必须确定它代表四种命名颜色中的哪一种：红色、绿色、蓝色或黄色。 四个相关的 RGB 三元组是`(255, 0, 0)`,`(0, 255, 0)`,`(0, 0, 255)`， 和`(255, 255, 0)`。 输出是相应的大写颜色名称。 

只有一个输入三元组，每个组件都有 256 个可能值的微小固定范围。 即使是检查每个可能的 RGB 三元组的算法也只会有`256^3 = 16,777,216`组合，尽管这里没有理由这样做。 由于所需的颜色是明确已知的，自然解决方案仅执行恒定数量的比较。 因此，时间和内存要求与输入值无关。 

主要的边缘情况是将黄色与三种原色区分开来。 例如，输入```
255 255 0
```必须产生```
YELLOW
```一个粗心的实现，只检查是否`R == 255`可以将其分类为红色，因为黄色的红色分量也处于最大值。 必须比较完整的三元组。 

另一个有用的边界情况是蓝色：```
0 0 255
```产生```
BLUE
```只检查一个组件是否存在`255`是不够的，因为每种有效颜色至少有一个分量等于`255`。 所有三个组件的位置决定了答案。 

该语句描述了与四种命名颜色之一相对应的输入，因此三元组例如`(0, 0, 0)`或者`(255, 255, 255)`超出了问题的有效输入域。 此类三元组不需要输出，并且解决方案不应为它们发明额外的颜色名称。 

## 方法

 强力解释将枚举每个可能的 RGB 三元组`(0, 0, 0)`通过`(255, 255, 255)`并将每个候选者与输入进行比较。 正好有`256^3 = 16,777,216`候选人，因此在最坏的情况下，这会执行大约 1700 万次检查。 这比问题所需的工作量要多得多。 

暴力破解之所以有效，是因为可能的 RGB 值集是有限的，并且四种目标颜色是已知的。 观察到只有四个三元组可以作为答案，因此我们可以删除整个枚举。 我们只需将输入三元组与这四个已知三元组进行比较并打印匹配的名称。 最多需要四次比较。 

这本质上是一个直接查找问题。 RGB 表示背后没有隐藏任何图形、动态编程状态、搜索空间或算术优化。 这三个数字只是四个固定值之一的紧凑编码。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(256^3) | O(256^3) | O(1) | O(1) | 正确但不必要的慢 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取三个整数`R`,`G`， 和`B`。 它们描述输入颜色的红色、绿色和蓝色强度分量。 
2. 比较`(R, G, B)`和`(255, 0, 0)`。 如果它们相等，则颜色为红色，因此打印`RED`。 
3. 否则与`(0, 255, 0)`。 相等意味着颜色是绿色，所以打印`GREEN`。 
4.否则将其与`(0, 0, 255)`。 相等意味着颜色是蓝色，所以打印`BLUE`。 
5. 如果这三个三元组都不匹配，则有效输入保证消失`(255, 255, 0)`作为剩余的可能性。 打印`YELLOW`。 

### 为什么它有效

 该算法根据每个可能的有效答案检查输入。 四个 RGB 三元组是不同的，因此输入无法匹配两种不同的颜色。 由于该问题保证输入代表这四种颜色中的一种，因此必须通过一次比较才能识别它。 因此，打印的名称是与输入 RGB 三元组关联的名称。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    r, g, b = map(int, input().split())

    if (r, g, b) == (255, 0, 0):
        print("RED")
    elif (r, g, b) == (0, 255, 0):
        print("GREEN")
    elif (r, g, b) == (0, 0, 255):
        print("BLUE")
    else:
        print("YELLOW")

if __name__ == "__main__":
    solve()
```第一行读取唯一的输入行并将其三个分量转换为整数。 由于只有一个测试用例，因此不存在测试用例循环。 

每个条件同时比较所有三个组件。 这避免了仅从一个组件识别颜色的常见错误。 例如，`R == 255`对于红色和黄色都适用，因此仅检查`R`无法区分它们。 

决赛`else`是安全的，因为输入保证代表四种颜色之一。 它也比编写第四个显式相等测试稍微干净一些。 不存在索引或边界问题，Python 整数可以轻松处理整个允许的范围。

## 测试用例

import io

def solve():
    r, g, b = map(int, input().split())

    if (r, g, b) == (255, 0, 0):
        print("RED")
    elif (r, g, b) == (0, 255, 0):
        print("GREEN")
    elif (r, g, b) == (0, 0, 255):

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    result = sys.stdout.getvalue()

assert run("0 0 255\n") == "BLUE\n", "blue"
assert run("255 255 0\n") == "YELLOW\n", "yellow boundary"

## 边缘情况

 黄色的情况最有可能导致逻辑错误。 对于准确的输入```
255 255 0
```与红色的第一次比较失败，因为绿色分量是`255`而不是`0`。 绿色比较也失败，因为红色分量是`255`。 蓝色比较失败，因为红色和绿色分量都没有所需的值。 算法到达最后一个分支并打印`YELLOW`，这是正确的。 

蓝色情况测试最大分量的位置。 为了```
0 0 255
```红色比较失败，因为`R`是`0`，绿色比较失败，因为`G`是`0`。 蓝色比较匹配所有三个组件和打印`BLUE`。 仅检查某个组件是否等于的解决方案`255`在这种区分上会失败。 

最小分量边界也被原色覆盖。 在```
0 255 0
```两个分量恰好处于其最小值`0`，而中间分量是`255`。 该算法比较整个三元组并正确打印`GREEN`。 

最后，最大RGB边界出现在```
255 255 0
```其中两个组件同时`255`。 该算法并不假设恰好有一个分量是最大的，因此它可以正确识别黄色。
