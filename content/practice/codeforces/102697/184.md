 ## 解决方案
 ## 问题理解

 我们得到一个正整数列表。 必须恰好删除一个整数，然后我们将每个剩余的整数相乘。 在删除的整数的所有可能选择中，我们需要输出最大可能的乘积。 

关键条件是每个值都是正的。 这消除了零或负数可能出现的复杂情况。 如果我们删除一个值`x`，所得产品包含所有其他值。 由于所有值都是正数，因此删除较小的值会比删除较大的值留下更大的乘积。 因此，整个问题简化为找到列表中的最小整数并将所有其他整数相乘。 

该声明没有发布有用的上限`n`在问题页面上，但时间限制只有一秒。 对每个可能省略的元素执行单独的乘积计算的算法需要`n(n-1)`乘法。 即使与`n = 100000`，这大约是`10^10`乘法，这远远超出了一秒解决方案的处理能力。 线性扫描是合适的目标。 

有一些边缘情况可能会导致粗心的实施失败。 用一个数字，例如```
1
7
```唯一合法的选择是删除`7`，留下空产品。 空产品的约定值为`1`，所以正确的输出是```
1
```从第一个输入值初始化其答案的实现将错误地产生`7`。 

相等的值是另一种简单的边界情况。 为了```
5
3
3
3
3
3
```每个选择都会删除相同的值，所以答案是`3 * 3 * 3 * 3 = 81`。 解决方案不得假设最小值出现在唯一位置。 

最小值也可以出现在任意位置。 为了```
4
8
2
5
7
```我们删除`2`，离开`8 * 5 * 7 = 280`。 意外删除第一个或最后一个元素的解决方案会产生错误的产品。 

## 方法

 直接的方法是尝试每一个可能被省略的元素。 对于每个索引，我们扫描整个数组，将除该索引之外的每个元素相乘，并保留最大的乘积。 这是正确的，因为每个合法结果都对应于一个省略的索引，因此检查所有索引会检查每个可能的答案。 然而，每个`n`选择需要`n - 1`乘法，精确给出`n(n-1)`最坏情况下的乘法是二次的。 

有用的观察来自于所有数字都是正数的事实。 假设总产品在概念上是`a1 * a2 * ... * an`。 

如果我们删除`ai`，结果是除`ai`。 比较两个选择，删除较小的值总是留下较大的乘积。 例如，如果我们有一个部分产品`P`包含除`x`和`y`，然后删除`x`给出`P * y`，同时去除`y`给出`P * x`。 如果`x < y`， 然后`P * y > P * x`。 

所以最优选择始终是删除最小元素。 我们可以在读取数组时找到该最小值，然后将除该最小值出现一次之外的每个元素相乘。 更简单的实现是计算每个元素的乘积并除以最小值，因为最小值保证是总乘积的一个因子。 Python 整数还可以避免计算过程中的溢出。 

比较结果为：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 对于大 n 来说太慢 |
 | 最佳| O(n) | O(n) | 已接受 |

 如果在读取时处理输入值，则最佳实现也可以是 O(1) 辅助空间，因为只需要总乘积和最小值。 

## 算法演练

 1. 阅读`n`和`n`正整数。 我们需要最小值，因为这是删除后留下最大可能乘积的值。 
2. 计算所有值的乘积并跟踪遇到的最小值。 保留总乘积可以避免为每个可能的遗漏重新计算几乎相同的乘积。 
3. 将总乘积除以最小值。 这从总乘积中恰好删除了一次最小值，这对应于省略元素的一种合法选择。 
4. 打印最终产品。 如果`n = 1`，总乘积等于唯一的元素，除以该元素得出`1`，正确代表空产品。 

### 为什么它有效

 让`m`是数组中的最小值，并令`P`是所有价值观的产物。 去除`m`产生`P / m`。 考虑任何其他值`x`。 自从`m <= x`并且所有剩余因素都是积极的，消除了`m`留下的产品至少与移除一样大`x`。 因此`P / m`是通过恰好删除一个元素可获得的最大乘积。 如果几个元素相等`m`，删除其中任何一个都会得到相同的结果，因此除以最小值仍然有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    values = [int(input()) for _ in range(n)]

    total = 1
    minimum = values[0]

    for x in values:
        total *= x
        if x < minimum:
            minimum = x

    print(total // minimum)

if __name__ == "__main__":
    solve()
```这`values`list 存储输入整数，以便可以一次性计算出总乘积和最小值。`total`开始于`1`，这是乘法恒等式，也使得`n = 1`案例工作自然而然。 

最小值初始化为`values[0]`而不是来自任意常数。 这可以避免当输入值大于该常数时意外选择不正确的最小值。 

乘法发生在最小比较与最终除法相关之前。 Python 的任意精度整数意味着中间总积不会像固定宽度的 C++ 或 Java 整数那样溢出。 该语句保证最终答案适合 32 位，尽管总乘积本身可能会大出等于省略值的一个因子。 

最终的整数除法是精确的，因为最小值是用于构造的因素之一`total`。

 对于示例 1，输入为：```

 | 步骤| 当前值| 最低 | 总产品 |

 | 1 | 3 | 3 | 3 |
 | 2 | 5 | 3 | 15 | 15
 | 3 | 6 | 3 | 90 | 90

 | 5 | 10 | 10 3 | 7200 | 7200
 | 决赛| | 3 | 7200 | 7200

 最小值是`3`，所以删除它留下`7200 / 3 = 2400`。 这与通过显式相乘获得的结果相匹配`5 * 6 * 8 * 10`。 

对于示例 2，输入为：```
4
4
3
2
1
```执行过程是：

 | 步骤| 当前值| 最低 | 总产品 |
 | ---| ---| ---| ---|
 | 开始| | 4 | 1 |

 | 决赛| | 1 | 24 |

 最小值是`1`，所以最优结果是`24 / 1 = 24`。 去除`1`不会改变乘积，这解释了为什么答案等于所有四个输入值的乘积。 

这些痕迹证明了中心不变量：处理任何前缀后，`total`是该前缀的乘积，并且`minimum`是其最小值。 最后，这两个值足以确定最佳省略。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个输入值都会被处理一次。 |
 | 空间| O(n) | 该实现存储了`n`输入值。 |

 该算法仅对列表执行一次线性传递，因此即使在以下情况下它仍然实用`n`很大。 在 Python 中，算术本身也是安全的，因为整数会根据需要自动增长，而问题保证最终答案适合 32 位有符号整数。 

通过在读取每个值时计算乘积和最小值，可以将辅助空间减少到 O(1)，而无需存储列表。 

## 测试用例```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())
    total = 1
    minimum = None

    for _ in range(n):
        x = int(input())
        total *= x
        if minimum is None or x < minimum:
            minimum = x

    print(total // minimum)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("5\n3\n5\n6\n8\n10\n") == "2400\n", "sample 1"
assert run("4\n4\n3\n2\n1\n") == "24\n", "sample 2"
assert run("5\n3\n3\n3\n3\n3\n") == "81\n", "sample 3"

# Minimum-size input
assert run("1\n7\n") == "1\n", "single element"

# Minimum at the beginning
assert run("4\n1\n5\n6\n10\n") == "300\n", "minimum at beginning"

# Minimum at the end
assert run("4\n8\n5\n6\n1\n") == "240\n", "minimum at end"

# Large stress case, with an answer that still fits comfortably
large_input = "100000\n" + ("1\n" * 99999) + "2\n"
assert run(large_input) == "1\n", "large input"

# Several equal minima
assert run("5\n2\n7\n2\n9\n4\n") == "504\n", "repeated minimum"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 |`1 / 7`|`1`| 省略唯一元素时的空乘积 |
 |`4 / 1 5 6 10`|`300`| 第一个位置的最小值 |
 |`4 / 8 5 6 1`|`240`| 最后位置的最小值 |
 |`100000`价值观，主要是`1`|`1`| 大输入上的线性行为 |
 |`5 / 2 7 2 9 4`|`504`| 多次出现最小值 |

 ## 边缘情况

 对于单元素输入，```
1
7
```该算法开始于`total = 1`并读到`7`, 给予`total = 7`和`minimum = 7`。 最终计算结果为`7 // 7 = 1`。 这正是所需的结果，因为省略唯一的元素就不会留下任何因子相乘。 

对于相同的值，```
5
3
3
3
3
3
```总产品变为`243`并且剩下最少的`3`。 除法给出`243 // 3 = 81`。 每个可能的省略都是等效的，因此无需识别最小值的特定出现。 

至少在开始时，```
4
1
5
6
10
```总产品是`300`最小值是`1`。 最终的答案是`300`。 去除`1`保持乘积不变，这是最大可能的结果，因为每一个其他遗漏都会删除一个大于`1`。 

至少在最后，```
4
8
5
6
1
```总产品是`240`最小值变为`1`仅当处理最终值时。 该算法不依赖于最小值的位置，因此它可以正确打印`240`。 

对于重复的最小值，```
5
2
7
2
9
4
```总产品是`1008`最小值是`2`。 除以出现一次`2`给出`504`。 删除任一`2`产生相同的剩余产品，因此仅跟踪最小值就足够了。
