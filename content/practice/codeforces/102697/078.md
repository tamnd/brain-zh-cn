 ## 解决方案
 ## 问题理解

 该模拟跟踪了美国累计感染人数。 令 (N) 为当前感染人数，令 (N_{\max}=328.2) 百万为曲线变平的人口，令 (a) 为特定测试案例的感染率。 

一天内，该模型给出的新感染人数为

 [
 \Delta N = a\left(1-\frac{N}{N_{\max}}\right)N。 
]

 由于一个时间步代表一天，因此通过将该数量添加到当前人口中即可获得第二天的人口。 初始感染人数为（1）。 我们需要第一天感染人数至少达到（3.2亿）百万。 每个测试用例提供不同的 (a) 值，答案是该速率所需的天数。 官方声明指定了一秒的时间限制和256 MB的内存，并给出了如下所示的采样率和答案。 

该声明没有提供测试用例数量或感染率的明确数字界限。 这使得输入约束方面的传统渐近最坏情况界限无法更精确地表述。 预期的模拟仅在采样率的数百次迭代中就达到了所请求的总体，因此相关的实现是每个模拟日的少量恒定浮点工作。 在一秒的限制下，执行与个人数量成比例的工作的方法将过于昂贵，因为目标本身是 3.2 亿人。 模拟的自然单位是一整天，而不是一个人。 

如果停止条件或初始状态处理不正确，有几种边界情况可能会改变答案。 例如，如果人口已达到目标，则所需的额外天数为零。 在这个问题中，实际的初始种群是（1），因此官方输入模型不会出现这种情况，但它解释了为什么循环应该在执行另一次更新之前测试目标。 

一个更相关的案例是人口超过目标的第一天。 答案是当天的指数，而不是前一天。 从概念上讲，如果第 (66) 天人口低于 (320) 百万，并且在第 (67) 天至少为 (320) 百万，则正确的输出将是`67`。 在检查人口后增加天数的循环可能会意外报告`66`。 

另一个边缘情况是目标附近的平坦因子。 当(N)接近(N_{\max})时，因子(1-N/N_{\max})变小，因此新增感染人数急剧减少。 将公式替换为 (aN) 将忽略此影响并过早达到目标。 

初始值也很重要。 从 (N=0) 开始，使每个后续增量为零，因为该公式包含 (N) 作为因子。 按照问题的指定，从 (N=1) 开始可以避免退化状态。 

## 方法

 暴力解释将在个人层面上模拟流行病。 我们每天都可以检查当前感染的人群，并反复确定感染是如何累积的。 即使这是确定性的，在大约 400 天的时间内处理多达 3.2 亿人，在大型案例中也需要大约 (320,000,000\times400=128) 十亿人级操作。 这无法轻松地适应一秒钟的时间限制。 

该方程已经给出了一整天的新感染总数，因此没有理由单独处理人员。 给定当前 (N)，一次乘法即可计算出一整天的增量。 我们更新

 [
 N \leftarrow N+a\left(1-\frac{N}{328200000}\right)N
 ]

 并重复直到 (N\ge320000000)。 

关键的观察结果是该问题给出了确定性重现。 一旦知道(N)和(a)，(N)的下一个值就完全确定了。 模拟中不存在隐藏的分支、搜索、图形遍历或优化问题。 我们只需要跟踪该循环，直到达到目标。 

因此，直接逐日重复已经是最佳的实用方法。 唯一有意义的优化是每天执行一次重复而不是每人一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 人级暴力破解| (O(DP)) | (O(1)) | (O(1)) | 太慢了|
 | 每日重现模拟 | 每个测试用例 (O(D)) | (O(1)) | (O(1)) | 已接受 |

 这里（D）是模拟天数，（P）是假设的人级方法正在处理的人口。 对于预期的速率，(D) 仅约为数百。 

## 算法演练

 1.读取测试用例数量并独立处理每个感染率。 每个测试用例都从相同的初始群体开始并使用相同的常量，因此用例之间不需要共享状态。 
2. 将当前感染人口设置为（N=1），并将经过的天数设置为零。 最初的感染者在第一个模拟日之前就已存在，因此该人群不得算作一天的新感染人数。 
3. 当(N<320000000)时，计算第二天的新增感染人数：

 [
 \Delta N=a\left(1-\frac{N}{328200000}\right)N。 
]

 因子 (1-N/N_{\max}) 表示根据模型尚未被感染的人口比例。 
4. 将 (N) 添加 (\Delta N)，然后将日计数器加一。 增量必须在日期计数器提前之前发生，因为新计算的人口属于第二天。 
5. 一旦 (N\ge320000000) 就停止并打印日计数器。 我们使用`>=`，而不是相等，因为递归使用浮点值，并且通常会穿过目标而不是精确地落在目标上。 

### 为什么它有效

 不变的是，在 (d) 次迭代之后，(N) 正是在 (d) 模拟天之后问题重复产生的总体，直至普通浮点舍入。 更新使用指定的感染方程，并从指定的初始种群 1 开始。 因此，每次迭代都代表额外的模拟日。 循环在模拟人口至少达到 3.2 亿的第一次迭代时终止，因此报告的计数器恰好是所需的第一个天。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

N_MAX = 328_200_000.0
TARGET = 320_000_000.0

def days_to_target(a):
    n = 1.0
    days = 0

    while n < TARGET:
        n += a * (1.0 - n / N_MAX) * n
        days += 1

    return days

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        a = float(input())
        ans.append(str(days_to_target(a)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```这些常量存储为浮点值，因为复发包含分数感染率，并且总体更新通常不是整数。 将总体保持为浮点数还可以避免在整数和浮点表示之间重复转换。`days_to_target`准确地包含算法的递归。`n`开始于`1.0`， 尽管`days`从零开始，因为模拟日尚未过去。 条件`n < TARGET`在每次更新之前检查，因此当循环退出时，`days`是人口达到所需阈值的第一天。 

在将新值分配给之前先计算表达式`n`。 这相当于使用当天开始时的人口来计算当天的感染人数。 在同一迭代中再次使用已经更新的群体将有效地模拟一天内的多次感染更新并产生不同的模型。 

在正常的竞争性编程环境中，Python 的浮点类型是 64 位 IEEE-754 double。 这里的人口值远远在其有用的精度范围内，并且对于预期输入只需要几百次更新。

 | 2 | 从第一天起更新人口 | 再次应用递归 |

## 测试用例

 官方声明提供了四个示例案例，但没有指定 (a) 的正式最小或最大界限。 因此，测试工具可以直接验证重复性，而不是假装存在记录的最大速率约束。```python
import sys
import io

N_MAX = 328_200_000.0
TARGET = 320_000_000.0

def days_to_target(a):
    n = 1.0
    days = 0

    while n < TARGET:
        n += a * (1.0 - n / N_MAX) * n
        days += 1

    return days

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []

    for _ in range(t):
        a = float(input())
        out.append(str(days_to_target(a)))

    return "\n".join(out)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    try:
        sys.stdin = io.StringIO(inp)
        return solve()
    finally:
        sys.stdin = old_stdin

# Provided sample
assert run("4\n.394\n.212\n.107\n.059\n") == "67\n118\n226\n403", "official sample"

# Small positive rate. This catches accidental zero-based initialization.
assert days_to_target(1.0) > 0, "initial population must be one"

# Equal rates must produce equal answers.
assert run("3\n.212\n.212\n.212\n") == "118\n118\n118", "all equal rates"

# A larger rate must reach the target sooner than a smaller rate.
assert days_to_target(0.394) < days_to_target(0.212), "rate ordering"

# Rates very close to each other should still be processed independently.
a = days_to_target(0.059)
b = days_to_target(0.060)
assert b < a, "boundary between nearby rates"

print("All tests passed.")

 ## 边缘情况

 初始人口正好是一个。 如果实现从零开始，则递归将永远产生零，因为 (N) 乘以整个感染项。 开始于`1.0`避免这种无声故障并遵循问题指定的初始条件。 

停止条件必须是`n < TARGET`， 不是`n <= TARGET`。 假设一天的更新将人口从 319,999,999 更改为 320,000,001。 正确答案是那一天，因为尽管人口从未达到 3.2 亿，但目标已经达到。 浮点模拟不太可能巧合地落在精确的整数目标上。 

平坦项在目标附近也变得显着。 例如，当 (N) 接近 3.282 亿时，表达式 (1-N/N_{\max}) 接近于零。 如果一个实现不小心写了`a * n`而不是`a * (1 - n / N_MAX) * n`，它消除了整个扁平化效果并产生了一个小得多的答案。 

最后，更新必须使用当天开始的人口。 正确的过渡是

 N+a\left(1-\frac{N}{N_{\max}}\right)N。 
]

 计算该表达式的一部分`N`然后修改`N`在完成表达式更改重复之前。 在Python中，在将其分配给之前写入整个右侧`n`自然地保留了所需的顺序。
