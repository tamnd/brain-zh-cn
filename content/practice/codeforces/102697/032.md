 ## 解决方案
 ## 问题理解

 该锁有 (n) 个独立的转盘。 对于 dial (i)，允许的值形成从下限 (L_i) 到上限 (R_i)（含）的每个整数。 完整的锁组合为每个拨盘选择一个允许的值。 

任务是计算有多少种不同的完整组合是可能的。 由于一个刻度盘的选择不会限制另一个刻度盘的选择，因此答案是每个刻度盘上可用值数量的乘积。 存档的声明给出了输入格式和示例，但没有发布 (n) 或拨号限制的明确数字界限。 它确实指定了一秒的时间限制和 256 MB 的内存限制。 

对于具有限制 (L_i) 和 (R_i) 的单个刻度盘，可能的设置数量为

 [
 R_i-L_i+1。 
]

 (+1) 是必要的，因为两个端点都是允许的。 例如，范围 (3) 到 (7) 包含 (3,4,5,6,7)，即五个值。 

关键的约束结果是我们不应该自行构建组合。 如果每个刻度盘只有 (k) 个可能的值，则有 (k^n) 个完整的组合。 即使 (k=2)，这也已经是 (2^n)，因此随着 (n) 的增长，枚举组合变得不可行。 最佳解决方案只需要读取每个表盘一次，从而给出表盘数量的线性时间。 

在一些小情况下，实现可能会默默地犯一个相差一的错误。 有输入`1`其次是`3 3`，正确的输出是`1`，因为唯一可能的设置是 (3)。 (R-L) 等公式会错误地产生零。 

有输入`1`其次是`1 2`，正确的输出是`2`，因为旋钮可以设置为 (1) 或 (2)。 同样，忘记包含的上端点将产生 (1)。 

第二个常见错误是将产品初始化为零。 用于输入`1`其次是`5 5`，将第一个计数乘以零将使答案永远保持为零。 该乘积必须从 (1) 开始，即乘法恒等式。 

## 方法

 直接的暴力方法是生成表盘设置的每种可能的组合并对其进行计数。 这是正确的，因为每个有效组合只生成一次，并且每个生成的组合对应于每个允许范围中的一个选择。 

问题在于组合的数量。 如果 dial (i) 有 (c_i=R_i-L_i+1) 个可能值，则组合总数为

 [
 C=\prod_{i=1}^{n}c_i。 
]

 生成所有这些已经需要 (\Theta(C)) 组合，并且如果实现为每个组合显式构造一个 (n) 值元组，它将执行 (\Theta(nC)) 工作。 例如，如果每个转盘都有两个选择，那就变成 (\Theta(n2^n))，这很快就变得不可能了。 

消除这种指数工作的观察结果是刻度盘是独立的。 为一个转盘选择一个值绝不会改变另一个转盘的可用值。 当第一个转盘有 (c_1) 个选择、第二个转盘有 (c_2) 个选择等时，每个第一个转盘选择都可以与每个第二个转盘选择配对，从而给出 (c_1c_2) 个可能性。 对其余的转盘重复相同的推理即可得到完整的产品。 

因此，我们不构造任何组合，而是只计算每个转盘提供的选择并将其乘以答案。 这将问题从枚举指数数量的对象减少为每个输入刻度盘一次算术运算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (\Theta(nC))，其中 (C=\prod_i(R_i-L_i+1)) | (\Theta(n)) 每个存储的组合 | 太慢了 |
 | 最佳 | (O(n)) | (O(n)) | (O(1)) 除了输入存储 | 已接受 |

 ## 算法演练

 1. 初始化`answer`至 (1)。 结果是一个乘积，因此 (1) 是正确的中性起始值。 
2. 读取当前刻度盘的下限和上限 (L_i) 和 (R_i)。 
3. 计算该拨盘的合法设置数量为(R_i-L_i+1)。 两个端点都属于该范围，因此仅差值就太小了。 
4. 乘法`answer`通过这个数量的设置。 每个现有的部分组合都可以与新表盘的每个设置配对，因此乘法将所有新形成的组合精确计算一次。 
5. 对所有 (n) 个转盘重复前三个步骤。 
6. 打印`answer`处理完所有表盘后。 此时它等于每个拨盘的选择数的乘积，这正是完整的锁组合数。 

### 为什么它有效

 处理完前 (k) 个刻度盘后，保持不变式`answer`等于这 (k) 个转盘的可能设置数量。 最初，没有处理任何转盘，并且只有一个空的部分选择，因此`answer = 1`。 当处理dial(k+1)时，假设有(c)个合法值。 现有的每一项`answer`部分组合可以使用每个 (c) 值进行扩展，从而准确地产生`answer * c`新的组合。 不会出现重复的组合，因为新拨号盘上的值唯一标识了选择的分机号。 因此，每次拨号后，不变式仍然成立，并且在所有 (n) 次拨号之后，乘积正是所需的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    answer = 1

    for _ in range(n):
        lower, upper = map(int, input().split())
        answer *= upper - lower + 1

    print(answer)

if __name__ == "__main__":
    solve()
```第一行读取拨号次数。 变量`answer`从 (1) 开始，因为解是乘积，而不是和。 

对于每个表盘，`upper - lower + 1`计算其可能设置的确切数量。 乘法立即将该拨号合并到组合总数中，因此无需存储以前的范围或生成任何实际的锁定组合。 

Python 整数会根据需要自动增长，因此该实现不存在使用 32 位或 64 位整数类型的语言可能遇到的固定宽度整数溢出问题。 这在这里特别有用，因为产品可能变得比单个拨号限制大得多。 

包含范围是主要的边界细节。 写作`upper - lower`每当一个范围恰好包含一个值时就会失败，并且会将所有其他范围少计数一。 

该循环正好处理 (n) 个输入行。 可能的拨号值上没有嵌套循环，这就是即使组合数量巨大，实现仍然快速的原因。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O(n)) | (O(n)) | 每个表盘仅被读取和处理一次。 |
 | 空间| (O(1)) | (O(1)) | 仅存储正在运行的产品和当前的一对限值。 |

 ## 边缘情况

 下限和上限相等的刻度盘仅提供一种选择。 对于输入```
1
5 5
```该算法计算 (5-5+1=1)，将初始答案 (1) 乘以它，然后打印`1`。 没有的公式`+1`会错误地声称存在零设置。 

恰好包含两个值的范围会暴露出相同的包含边界问题。 为了```
1
1 2
```该算法计算 (2-1+1=2)，对应于设置 (1) 和 (2)。 输出是`2`。 

如果每个拨盘只有一种可能的设置，则无论有多少个拨盘，整个锁都只有一种组合。 为了```
3
4 4
8 8
20 20
```每个刻度盘贡献 (1)，因此运行乘积仍为 (1)，输出为`1`。 这也证实了为什么初始产品一定是（1）。 

大量的表盘并不会改变算法结构。 和`100000`拨号盘和`7 7`每条线路、每个转盘都贡献一个选择。 该算法执行准确`100000`迭代和打印`1`，而不尝试构造任何组合。 

最后，组合的数量可以比标准 32 位整数大得多。 十个刻度盘与范围`1 100`有 (100^{10}=10^{20}) 种可能的组合。 Python 的任意精度整数允许精确计算乘积，因此不需要特殊的溢出处理。
