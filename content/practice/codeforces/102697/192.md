 ## 解决方案
 ## 问题理解

 我们有一个 8 × 8 的棋盘，其中包含几个马。 每个单元格要么是空的，表示为`.`，或包含一个骑士，由`K`。 骑士通过将一个坐标更改 2，将另一个坐标更改 1 来精确攻击可到达的单元格。我们必须标记至少一个骑士在一次移动中可到达的每个空单元格：`*`。 现有的骑士仍然存在`K`，并且保留所有其他空单元格`.`。 打印出最终的 8 x 8 板。 

电路板尺寸固定为 8 x 8，因此只有 64 个单元。 即使是执行数百或数千次操作的解决方案也非常快。 不需要复杂的图算法或广度优先搜索，因为我们只关心一个马的移动，而不关心涉及多个移动的路径。 特别是，最大可能的骑士数量为 64 个，每个骑士只有 8 个可能的移动偏移量，最多提供 512 个候选目的地可供检查。 

主要的边缘情况来自棋盘边界和重叠棋步。 角落里的骑士只有两次合法的动作。 例如，与```
K.......
........
........
........
........
........
........
........
```正确的输出是```
........
..*.....
.*......
........
........
........
........
........
```假设所有八个动作都留在棋盘内的粗心实现会在数组外部进行索引或标记无效位置。 

当几个骑士可以到达同一个空牢房时，就会发生另一个微妙的情况。 该单元格仍应仅包含一个`*`，因为输出描述的是单元格是否可达，而不是有多少骑士到达它。 例如，```
........
..K.....
........
.K......
........
........
........
........
```两个骑士都可以到达的单元格。 分配`*`而不是增加计数器自然可以处理这种情况。 

第三种情况是目的地已经包含骑士。 输出必须保留`K`而不是将其替换为`*`。 例如，```
K.......
........
..K.....
........
........
........
........
........
```有一个骑士在`(0, 0)`可以达到`(2, 1)`，但该目的地已经被另一位骑士占据，所以它仍然存在`K`。 如果不小心地无条件标记每个可到达的单元格，就会破坏原始的棋盘信息。 

## 方法

 一个简单的暴力解决方案可以检查每个棋盘单元并询问是否至少有一个骑士可以移动到它。 对于每个目的地，我们可以检查每个单元格作为可能的骑士并测试八个骑士偏移。 具有 64 个可能的目的地、64 个可能的源单元和 8 个偏移量，最坏的情况执行`64 * 64 * 8 = 32,768`移动检查。 这对于这个特定的板来说很小，所以这种方法实际上足够快。 

更直接的方法是从骑士开始。 每当我们遇到一个`K`，我们尝试所有八种可能的骑士动作。 如果目的地位于 8 x 8 板内并且当前包含`.`，我们将其更改为`*`。 每个骑士最多贡献 8 个检定，因此 64 个骑士最多有`64 * 8 = 512`候选人的举动。 

关键的观察结果是，该问题要求单元格可以一次性到达。 我们不需要搜索中间位置。 骑士的完整可能单步目的地集合是预先已知的，因此每个骑士都可以独立处理。 这减少了从检查每个源-目的地对到仅检查每个实际骑士的八个几何可能目的地的工作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(64² × 8) | 奥(64) | 已接受，但不必要的工作 |
 | 最佳| O(64 × 8) | 奥(64) | 已接受 |

 由于 64 是一个常数，因此从技术上讲，两种方法的输入大小都是 O(1)。 第二种方法仍然更可取，因为它直接表达问题的结构并避免检查不是骑士的细胞。 

## 算法演练

 1. 将八个棋盘行读入可变的 8 x 8 字符网格中。 保持网格可变让我们可以编写`*`直接进入可到达的空单元格。 
2. 扫描每一行和每一列。 当当前单元格包含`K`，将其视为一马动作的源位置。 
3. 对于那个骑士，尝试八个位移对`(2,1)`,`(2,-1)`,`(-2,1)`,`(-2,-1)`,`(1,2)`,`(1,-2)`,`(-1,2)`， 和`(-1,-2)`。 这些正是向一个方向移动两个单元和垂直于该方向移动一个单元的合法方法。 
4. 对于每个目的地，首先检查其行和列是否在`0`和`7`。 超出此范围的棋步将离开棋盘，必须被忽略。 
5. 如果目的地在棋盘内并且包含`.`，将其替换为`*`。 我们故意不更换`K`，因为骑士必须在输出中保持可见。 重复到达同一个单元格是无害的，因为分配`*`再次并不会改变结果。 
6. 处理完每个马后，打印结果的八行。 每个标记的单元格至少可以由一名骑士到达，而每个未标记的空单元格都无法通过任何合法的移动到达。 

### 为什么它有效

 不变量是，在处理骑士的任何前缀后，每个`*`至少一名经过处理的骑士可以通过一次合法的移动到达棋盘上，并且每个经过处理的骑士的每个合法目的地都已被标记，除非该目的地已被骑士占据。 当处理新的骑士时，将检查所有八个且仅八个可能的骑士目的地，因此不变量被扩展到该骑士而不会引入无效目的地。 处理完所有马后，已考虑了所有可能的单步目的地，这意味着最终的棋盘恰好包含所需的可到达的空单元格。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    board = [list(input().strip()) for _ in range(8)]

    moves = [
        (2, 1), (2, -1),
        (-2, 1), (-2, -1),
        (1, 2), (1, -2),
        (-1, 2), (-1, -2)
    ]

    for r in range(8):
        for c in range(8):
            if board[r][c] != 'K':
                continue

            for dr, dc in moves:
                nr = r + dr
                nc = c + dc

                if 0 <= nr < 8 and 0 <= nc < 8:
                    if board[nr][nc] == '.':
                        board[nr][nc] = '*'

    for row in board:
        print(''.join(row))

if __name__ == "__main__":
    solve()
```该板存储为列表而不是字符串，因为单个单元格需要从`.`到`*`。 这`moves`数组包含所有八个合法的骑士位移，因此不需要单独的水平和垂直移动的特殊情况。 

边界检查使用`0 <= nr < 8`和`0 <= nc < 8`。 Python 使用从零开始的索引，因此有效的行索引和列索引恰好是`0`通过`7`。 访问前检查目的地`board[nr][nc]`防止无效的数组访问。 

条件`board[nr][nc] == '.'`也是故意的。 目的地包含`K`必须保持骑士身份。 目的地已包含`*`不需要特殊处理，因为分配`*`再次会产生完全相同的效果。 

不存在整数溢出问题，因为该算法仅存储字符和坐标。 对于如此小的输入来说，快速 I/O 实际上并不是必需的，但是`sys.stdin.readline`遵循标准的竞争性编程输入模式。

 ## 边缘情况

 左上角的骑士只有两个合法目的地。 和```
K.......
........
........
........
........
........
........
........
```该算法会尝试所有八个偏移量。 六个产生负行或列索引并被边界条件拒绝。 两个有效目的地是`(1,2)`和`(2,1)`，所以输出是```
K.......
..*.....
.*......
........
........
........
........
........
```多个骑士可能会到达同一个牢房。 假设两个骑士在各自的移动循环中产生相同的目的地。 第一骑士的变化`.`到`*`; 当第二个骑士到达相同位置时，牢房已经`*`。 该条件仅作用于`.`，所以结果仍然是一个`*`。 这代表可达性而不是攻击骑士的数量。 

一个骑士也可以瞄准另一个骑士。 考虑```
K.......
........
..K.....
........
........
........
........
........
```骑士在`(0,0)`可以达到`(2,1)`，但是该单元格包含`K`。 实施检查`.`写之前`*`，所以第二个骑士保持不变。 这保留了占用的单元和空的可到达单元之间所需的区别。 

最后，不包含马的棋盘应该保持完全不变。 由于外部扫描永远不会进入移动循环`board[r][c] != 'K'`，任何细胞都不会意外地变成`*`。 相反，如果每个单元格都包含一名骑士，则所有可能的目的地都被占据，因此棋盘也保持不变。 这些情况自然会从相同的两次检查中得出，而不需要特殊情况的代码。
