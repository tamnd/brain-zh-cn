 ## 解决方案
 ## 问题理解

 该问题要求我们计算几个杠杆的机械效益。 对于每个测试用例，我们给出两个正长度，`A`和`B`，代表杠杆的两侧。 机械效益是这些长度的比率，因此所需的值为`A / B`。 第一个输入整数告诉我们接下来有多少个杠杆描述，以及接下来的每个杠杆描述`n`行包含一对`A B`。 我们为每一对打印一个实数。 官方的例子证实了正比，比如`10 / 5 = 2.0`和`2 / 3 = 0.6666666666666666`。 

已发表的声明并未提供明确的数字界限`n`,`A`， 或者`B`，但时间限制只有1秒，内存限制为256MB。 幸运的是，每个测试用例只需要一次算术运算，因此即使大量的用例也可以在线性时间内处理。 这里没有理由考虑二次或指数算法。 主要的实现问题是将除法生成为浮点值，而不是意外地执行整数除法。 

简单的边缘情况是等边。 用于输入`1`其次是`5 5`，答案是`1.0`。 使用整数除法的实现仍然会产生`1`，它在数值上是正确的，但不遵循问题所演示的浮点输出。 

更能说明问题的是分子较小，例如输入`1`其次是`2 3`。 正确的输出是`0.6666666666666666`。 粗心的整数除法实现会产生`0`，完全失去机械优势。 

双方的顺序也很重要。 用于输入`1`其次是`3 2`，答案是`1.5`， 不是`0.6666666666666666`。 将比率视为无序对或反转操作数会改变两侧的物理含义。 

## 方法

 最直接的方法是独立处理每个杠杆。 读`A`和`B`， 计算`A / B`，并立即打印结果。 这已经是最佳渐近解，因为必须读取每个输入对，并且每个输入对都有一个必须计算的不同答案。 

问题背后没有隐藏任何有意义的更快算法。 假设的强力方法可能会花费额外的工作来尝试通过重复减法或搜索十进制表示来得出比率。 这种做法原则上是正确的，但是却进行了不必要的操作。 例如，计算`10 / 5`通过重复减法需要几步而不是一次除法，并且对于大值，运算次数随着数字的大小而增加。 如果输入包含`n`与大值配对，这可能会比所需的要昂贵得多`n`部门。 

关键的观察是公式本身已经给出了答案。 不同杠杆之间没有交互，没有对可能的配置进行优化，也没有需要从一个测试用例转移到另一个测试用例的状态。 一次`A`和`B`已知，答案完全由下式决定`A / B`。 

因此，最佳解决方案只需对每个测试用例执行一次浮点除法。 它的运行时间与输入对的数量成线性关系，并且其额外的内存使用量是恒定的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 重复减法实现中的 O(n · max(A, B)) | O(1) | O(1) | 对于大值来说太慢 |
 | 直属部门| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取杠杆配置的数量，`n`。 这准确地告诉我们必须处理多少对。 
2. 重复`n`次并读取两个正长度`A`和`B`。 每对都是独立的，因此不需要存储以前的对。 
3. 计算`A / B`使用Python的`/`操作员。 蟒蛇的`/`始终执行浮点除法，这正是输出所需要的。 
4. 打印结果值。 Python 的标准浮点表示与这些普通整数输入的示例中显示的表示相匹配。 

### 为什么它有效

 对于每个杠杆，机械效益由两侧长度之比定义，其中`A`作为分子和`B`作为分母。 该算法为每个输入对精确计算一次该比率并将其打印出来。 由于每个测试用例都是独立的，因此一次处理一个测试用例不会影响任何其他答案。 因此，每个印刷值都是所需的机械优势。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    for _ in range(n):
        a, b = map(int, input().split())
        print(a / b)

if __name__ == "__main__":
    solve()
```第一行读取测试用例的数量。 然后循环准确执行`n`次，因此不存在意外处理额外行或跳过一对的风险。 

表达式`a / b`是故意使用而不是`a // b`。 前者产生浮点除法，而后者丢弃小数部分。 这种区别对于以下情况至关重要：`2 3`，其答案大约为`0.6666666666666666`。 

问题陈述保证分母为正，因此除以零不需要特殊处理。 Python 整数还可以避免读取输入时溢出，并且实际除法由 Python 的浮点算术处理。 

输入被处理为`sys.stdin.readline`，根据快速竞争编程 I/O 的需要。 不需要数组，因为每个答案都可以在读取其对应的对后立即打印。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个`n`杠杆配置需要一次分割和一次输出操作。 |
 | 空间| O(1) | O(1) | 仅存储当前的边长对。 |

 该解决方案对每个输入对执行恒定的工作，因此其运行时间随着配置数量线性增长。 对于 1 秒的限制，这是适当的复杂性，并且恒定的内存使用量完全低于问题指定的 256 MB 限制。

import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())

    for _ in range(n):
        a, b = map(int, input().split())
        print(a / b)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample

    "10 5\n"
    "2 3\n"
    "7 5\n"

    "1.4\n"
    "2.5714285714285716\n"
), "sample 1"

# Minimum-size style case

# All values equal

    "5 5\n"
    "100 100\n"
    "999 999\n"
    "1000000 1000000\n"
) == (

    "1.0\n"

), "all equal values"

 ## 边缘情况

 直接处理相等的边长，因为除法给出了精确的结果`1.0`。 对于输入`1`其次是`5 5`，算法读取`A = 5`和`B = 5`，计算`5 / 5`，并打印`1.0`。 没有特殊情况是必要的。 

小数结果的处理也无需额外的逻辑。 对于输入`1`其次是`2 3`，算法评估`2 / 3`，生产`0.6666666666666666`使用 Python 的标准浮点表示。 整数除法的实现会错误地产生`0`。 

操作数顺序被保留。 对于输入`1`其次是`3 2`，算法计算`3 / 2 = 1.5`。 反转该对会产生`2 / 3`，因此有必要将这两个值读入正确的分子和分母。 

大值在 Python 中不需要特殊的溢出处理。 为了`1`其次是`1000000000 1`，算法计算`1000000000 / 1`和打印`1000000000.0`。 无论正输入值的大小如何，都适用相同的恒定工作方法。 

最后，大量独立的测试用例不需要存储整个输入结构。 每对都会被立即读取、划分和打印。 因此，即使配置数量很大，内存消耗也保持恒定。
