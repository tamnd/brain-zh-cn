 ## 解决方案
 ## 问题理解

 商店按固定周期排列了三个部分：农产品，然后是肉类，然后是干货，最后回到农产品。 在商店的一个完整循环中，您最多可以从每个部分收集一件商品。 

对于一个测试用例，三个整数`p`,`m`， 和`d`告诉我们分别需要多少农产品、肉类和干货物品。 我们需要找到收集所有请求的项目所需的最小完整循环数。 原来的问题有`n`测试用例，并且每个测试用例恰好包含这三个量。 

关键约束实际上并不是数值限制`p`,`m`， 或者`d`。 已发布的声明没有给出这三个值的明确上限，因此运行时间取决于它们的大小的算法存在不必要的风险。 最佳解决方案应仅取决于一个测试用例中的恒定数量。 由于只有三个部分，因此恒定时间是可能的。 

第一种边缘情况是一个部分比其他部分需要更多的物品。 例如，```
1
1 5 2
```答案是`5`。 肉需要五个项目，而我们每个循环只能获取一个肉项目，因此四个循环可能不够。 将项目总数除以三的粗心解决方案将计算`8 / 3`，这只是`2`与整数除法显然是不够的。 

第二种边缘情况是所有三个量都相等。```
1
4 4 4
```答案是`4`。 每个循环可以从每个部分收集一个项目，因此四个循环可以收集每个部分的四个项目。 模拟给出了相同的结果，但它执行了不必要的工作。 

第三种边缘情况是只有一个部分有任何东西可以收集。```
1
0 0 7
```答案是`7`。 我们仍然需要七个循环，因为干货每个循环只能贡献一项。 基于请求项目总数的解决方案可能会错误地假设在一次访问同一部分期间可以收集多个项目。 

## 方法

 直接模拟可以重复走完这三个部分。 在每个循环中，如果有剩余，则需要一件农产品物品；如果有剩余，则需要一件肉类物品；如果有剩余，则需要一件干货物品。 当所有三个计数器都达到零时，该过程停止。 这是正确的，因为每个循环恰好对应于从每个部分获取一项的一次机会。 

如果`L = max(p, m, d)`，模拟执行准确`L`循环。 由于每个循环检查三个部分，因此它执行`3L`部分操作。 因此它的运行时间是`O(max(p, m, d))`。 对于大批量来说，这可能会变得不必要的昂贵，即使答案是由最大的需求立即确定的。 

关键的观察结果是，每个循环为每个部分提供了一个容量单位。 假设 Produce 需要`p`项目。 没有任何策略可以在少于`p`循环，因为每个循环最多可以收集一个 Produce 项目。 同样的论证给出了下界`m`和`d`循环。 因此，每个有效的解决方案至少需要`max(p, m, d)`循环。 

该下限也是可以实现的。 如果我们准确执行`max(p, m, d)`循环中，每个部分都会获得足够的机会，因为其所需的项目数最多为该最大值。 较早完成的部分只是停止获取物品，而其他部分继续进行。 因此，最小值恰好是三个量中最大的一个。 

强力模拟之所以有效，是因为它正确地模拟了每个单独的循环，但未能利用所有循环都是相同的事实。 观察到只有最慢完成的部分决定循环数，从而将整个问题减少到一个`max`手术。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(最大(p, m, d)) | O(1) | O(1) | 正确，但对于大值来说速度不必要地慢 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 每个测试用例都是独立的，因此可以将相同的恒定时间计算应用于每个用例。 
2. 阅读`p`,`m`， 和`d`，所需数量的农产品、肉类和干货。 
3. 计算`max(p, m, d)`。 这是一个下限，因为需求最大的部分每个循环只能提供一项。 
4. 输出最大值。 所需项目的最大数量也足够了，因为经过多次循环后，每个部分都至少拥有与其所需项目数量一样多的收集机会。 

正确性来自匹配下限和上限。 让`L = max(p, m, d)`。 任何解决方案至少需要`L`循环，因为需要的部分`L`items 每个循环只能提供一项。 另一方面，之后`L`循环，Produce 已经有`L`机会，肉有过`L`机会，干货已经有了`L`机会。 由于每个所需数量最多为`L`，所有要求的物品都可以收集。 因此最小循环数恰好是`L`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    out = []
    for _ in range(t):
        p, m, d = map(int, input().split())
        out.append(str(max(p, m, d)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```第一行给出了独立测试用例的数量，因此程序可以准确地处理`t`三倍。 使用`input = sys.stdin.readline`遵循所请求的快速输入模式，尽管数据量足够小，普通输入也足够了。 

对于每个测试用例，`map(int, input().split())`阅读三部分要求。 表达式`max(p, m, d)`直接实现上面证明的数学结果。 

答案将附加到列表中并在最后打印一次。 这避免了重复写入标准输出，并且每行只产生一个答案。 

没有边界计算或索引，因此不存在相差一的问题。 Python 整数还可以处理任意大的值，因此实现不需要特殊的整数类型。 

## 工作示例

 对于第一个样本，要求是`2`,`6`， 和`1`。 肉需要六样东西，所以六环是不可避免的。 六环也为农产品和干货提供了足够的机会。 

| 循环| 生产剩余 | 剩余肉 | 剩余干货 |
 | --- | --- | --- | --- |
 | 开始| 2 | 6 | 1 |
 | 1 | 1 | 5 | 0 |
 | 2 | 0 | 4 | 0 |
 | 3 | 0 | 3 | 0 |
 | 4 | 0 | 2 | 0 |
 | 5 | 0 | 1 | 0 |
 | 6 | 0 | 0 | 0 |

 该算法跳过此模拟并立即计算`max(2, 6, 1) = 6`。 

对于第三个样本，要求是`1`,`5`， 和`7`。 

| 循环| 生产剩余 | 剩余肉 | 剩余干货 |
 | --- | --- | --- | --- |
 | 开始| 1 | 5 | 7 |
 | 1 | 0 | 4 | 6 |
 | 2 | 0 | 3 | 5 |
 | 3 | 0 | 2 | 4 |
 | 4 | 0 | 1 | 3 |
 | 5 | 0 | 0 | 2 |
 | 6 | 0 | 0 | 1 |
 | 7 | 0 | 0 | 0 |

 干货是限制版块，所以答案是`max(1, 5, 7) = 7`。 该跟踪说明了为什么提前完成的部分不会减少另一部分所需的循环数量。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个`n`测试用例执行一项`max`操作|
 | 空间| O(n) | 所有测试用例的输出字符串在打印之前都被存储 |

 无论请求的数量有多大，每个测试用例的工作量都是恒定的。 凭借Codeforces声明给出的一秒和256MB的限制，该算法具有极大的安全裕度，因为其运行时间仅取决于测试用例的数量，而不取决于`p`,`m`， 或者`d`。

import io

def solve():
    input = sys.stdin.readline
    t = int(input())

    out = []
    for _ in range(t):

    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 边缘情况

 当所有要求都为零时，输入```
1
0 0 0
```根本不需要穿过商店。 该算法计算`max(0, 0, 0) = 0`和打印`0`。 在检查计数器之前无条件执行一个循环的模拟将错误地产生`1`。 

当某一部分占主导地位时，请考虑```
1
1 5 2
```最大值为`5`。 农产品在第一个循环后完成，干货在第二个循环后完成，但肉类还需要三个机会。 该算法正确地忽略已经完成的部分并返回`5`。 

当所有部分都有相同的要求时，```
1
4 4 4
```每个循环可以从每个部分收集一个项目。 四次循环后，所有三个计数器都为零，所以答案是`4`。 这证实了最大值不仅仅是下限，而且始终是可以实现的。 

最后，考虑一个非常大的需求：```
1
0 0 1000000000
```答案是`1000000000`。 逐个循环的模拟需要十亿次迭代，而最佳算法执行一次`max`手术。 这个例子抓住了恒定时间观察更可取的核心原因。
