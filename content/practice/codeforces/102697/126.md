 ## 解决方案
 ## 问题理解

 我们有一个逐条描述的地铁网络。 每条地铁线路都以车站名称的有序序列给出，如果一个车站属于至少两条不同的地铁线路，则该车站就是换乘站。 

线路内车站的顺序不会影响答案。 重要的是每个车站包含哪些线路。 环线产生了一个微妙之处：同一个车站可以在一条线上多次出现，包括在路线的两端。 这样的重复仍然代表只有一条地铁线路经过该车站，因此不能使该车站看起来像换乘站。 

例如，与```
1
3
A B A
```只有一行，所以正确的输出是空的。 粗心的基于频率的解决方案会看到`A`两次并错误地将其归类为中转站。 

和```
2
2
A B
2
B C
```唯一的中转站是`B`，所以输出是```
B
```当前 Codeforces 页面上的声明文本表示在名称前打印中转站的数量，但官方示例省略了该数字并仅打印名称。 这些示例可靠地指示了所需的输出格式，因此下面的解决方案按字母顺序打印每个传输站一次，没有计数行。 

可用声明没有提供线路数量或每条线路的车站数量的明确数字界限。 时间限制为 1 秒，内存限制为 256 MB。 这使得反复比较每条线路与其他线路的方法变得不必要地昂贵，特别是当车站出现的总数很大时。 我们希望工作基本上与输入大小成正比，只增加所需的排序成本。 

主要的边缘情况来自于区分站点出现与线路成员资格。 在一个循环中出现多次的电台必须对该线路仅计数一次。 例如，```
1
5
East North West South East
```没有中转站，因此输出为空。 计算出现次数会错误地报告`East`。 

包含同一车站的两条不同线路必须算作换乘，即使该车站在任一线路上出现多次也是如此。 例如，```
2
3
A B A
2
C A
```有输出```
A
```因为`A`属于两条不同的线。 在更新全局信息之前对每行进行重复数据删除可以正确处理此问题。 

按字母顺序排列是正确的电台集仍然可能产生错误答案的另一个地方。 为了```
3
2
Z A
2
M Z
2
A M
```三个站都是中转，正确的输出是```
A
M
Z
```路由顺序不能用作输出顺序。 

## 方法

 直接的暴力解决方案可以比较每对地铁线路并找到该对地铁线路共享的车站。 这是正确的，因为当一个车站出现在至少两条不同的线路中时，它就是一个换乘站，因此每个换乘站必须在至少一次成对比较中被发现。 

问题在于重复工作量。 如果有`n`行，每行最多包含`m`站的出现，比较每一对可能需要粗略的`O(n^2 * m)`当比较直接扫描路线时起作用。 为了`n`长度线`m`， 有`n(n-1)/2`成对，每对可能需要检查`m`一条或两条路线的车站。 即使首先将路线转换为集合，检查每对路线的成本仍然大约为`O(n^2)`设置比较并且可能变得比必要的大得多。 

蛮力之所以有效，是因为共享成员资格正是中转站的定义，但它多次提出相同的问题。 关键的观察是，要构建的自然对象不是线路对的集合，而是从每个站点到包含它的线路的反向映射。 

读行时`i`，我们可以先将其电台放入一个集合中。 然后，对于该线路上的每个不同站点，我们记录该线路`i`包含它。 在处理完所有线路后，当该站的线路标识符集的大小至少为 2 时，该站就是换乘站。 

这将问题从重复比较行改为每次输入发生时积累信息。 如果`S`是站点出现的总数，`U`是不同车站名称的数量，构建映射需要`O(S)`哈希集和字典的预期时间。 对答案进行排序需要`O(K log K)`， 在哪里`K`是换乘站的数量。 自从`K <= U`，总计为`O(S + U log U)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 最坏情况下的 O(n²m) | O(纳米) | 太慢了 |
 | 反向车站到线路映射 | O(S + U log U) | O(S + U log U) | O(U + S) | 已接受 |

 ## 算法演练

 1. 创建一个字典，将每个车站名称映射到一组地铁线路标识符。 该集合是必要的，因为同一个站点可以在一条环路上出现多次。 
2. 读取每条地铁线路并为其分配唯一的线路标识符。 在更新字典之前，将该线路的车站序列转换为集合。 
3. 对于当前线路上的每个不同车站，将当前线路标识符插入到该车站集合中。 经过此操作后，该集合准确地代表了经过车站的不同地铁线路。 
4. 处理完所有行后，检查字典中的每个电台。 如果其行标识符集的大小至少为 2，则将其名称添加到答案中。 
5. 按字母顺序对转运站名称进行排序。 该问题要求按字母顺序输出，并且输入顺序与字母顺序无关。 
6. 打印排序后的名称，每行一个。 按照提供的示例，不会打印单独的计数。 

### 为什么它有效

 对于每个车站`x`，保持不变式`lines[x]`正是包含不同地铁线路的集合`x`。 当一条线路被处理时，取一组它的站点可以保证重复出现`x`在同一行上仅添加一个行标识符。 相反，每行包含`x`提供自己的标识符，因此在读取所有输入后，`|lines[x]|`等于经过的不同线的数量`x`。 根据定义，`x`当该值至少为 2 时，就是一个中转站。 因此，该算法精确地选择所有转运站，并对它们进行排序以产生所需的顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    station_lines = {}

    for line_id in range(n):
        m = int(input())
        stations = set(input().split())

        for station in stations:
            if station not in station_lines:
                station_lines[station] = set()
            station_lines[station].add(line_id)

    answer = [
        station
        for station, lines in station_lines.items()
        if len(lines) >= 2
    ]

    answer.sort()

    sys.stdout.write("\n".join(answer))

if __name__ == "__main__":
    solve()
```字典`station_lines`是输入的反向表示。 它不是只存储路线，而是记录与每个车站相关的线路，这直接匹配换乘站的定义。 

这`set(input().split())`操作是循环线的关键细节。 假设一条路线是`A B C A`。 迭代原始列表将插入相同的行标识符`A`两次，这不会更改 Python 集合，但显式地将路由转换为集合也可以避免执行字典更新两次。 更重要的是，它使线条的预期解释变得清晰。 

行标识符是从零开始的循环索引。 它的实际数值并不重要。 只有标识符之间的相等才重要，因为两个相等的标识符意味着出现的事件来自同一条地铁线路。 

测试`len(lines) >= 2`检查不同的线而不是全站仪的出现情况。 这正是真正的传输与循环的重复端点的区别。 

最后，`answer.sort()`提供字典顺序。 车站名称是字符串，因此 Python 的标准字符串排序与问题车站名称的字母顺序相匹配。 

整数不可能溢出，因为该算法仅执行设置大小和索引。 该实现还使用`sys.stdin.readline`根据需要，当总输入可能很大时，这是合适的。

 对于示例 1，重要的状态是与每个站点关联的线路标识符集。 第一行仅向其自己的站点提供标识符。 随着后续线路的处理，共享站会积累额外的标识符。 

| 线路| 车站| 处理后的不同行标识符 |

## 复杂度分析

 让`S`是所有地铁线路上车站出现的总数，`U`不同站名的数量，以及`K`换乘站的数量。 

| 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 预期 O(S + U log U) | 每个输入事件都通过哈希集或字典进行处理，然后最多`U`传输名称已排序 |
 | 空间| O(S + U) | 车站到线路的映射存储线路成员资格信息和所有不同的车站名称 |

 该算法基本上只处理一次输入，并且不会在地铁线路之间进行成对比较。 对于 1 秒的限制，这是适当的缩放比例，因为工作量随着输入中实际存在的信息量而不是行数的平方而增长。

 ## 边缘情况

 环线是最重要的边缘情况。 考虑```
1
5
A B C D A
```该算法将路径转换为`{A, B, C, D}`在更新映射之前。 每个站接收单线标识符`0`，因此每个行成员集都有大小 1。 答案是空的。 仅计算站点出现次数的解决方案会错误地考虑`A`转移。 

两条线路共享的车站通过累积不同的标识符来处理。 为了```
2
3
A B A
2
C A
```第一行给出`A`集合`{0}`。 第二行将其更改为`{0, 1}`。 它的大小是二，所以`A`被选择并打印一次。 

字母顺序与输入顺序无关。 为了```
3
2
Z A
2
M Z
2
A M
```该映射将所有三个车站标识为换乘站。 然后将答案列表排序为`A`到`Z`，生产```
A
M
Z
```不包含与另一条线路共享的车站的线路对答案没有任何贡献，无论它包含多少个车站。 例如，```
2
3
A B C
3
D E F
```让每个车站与一条线路相关联，因此输出为空。 对于这种情况，算法不需要特殊情况，因为最终的集合大小测试会自然地处理它。 

提供的样本中缺少传输计数也是输出格式的边缘情况。 尽管 Codeforces 页面上的文字描述了计数后跟电台名称，但实际示例仅包含电台名称。 实现遵循这些示例，这是法官对此存档问题所期望的格式。
