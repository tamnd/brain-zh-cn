 ## 解决方案
 ## 问题理解

 罐子开始于`n`糖果。 之后，从糖果被盗的第一天开始，我们会得到每个观察日罐子中仍然存在的糖果数量。 每天，我们需要确定自上次观察以来有多少糖果消失了。 

第一个观察值与原始量进行比较`n`。 以后的每次观察都会与前一天的剩余量进行比较。 如果剩余金额是`n = 100`， 其次是`97 92 85`,

 那么盗窃行为是`100 - 97 = 3`,`97 - 92 = 5`， 和`92 - 85 = 7`。 

每个观察日的输出包含一个整数，表示当天被盗的糖果数量。 

已发布的问题没有指定每日观察数量的有用上限，因此最安全的复杂性目标与输入量呈线性关系。 由于每个剩余糖果值必须至少检查一次才能产生相应的答案，`O(m)`时间`m`观察结果是最优的。 二次方法会反复重新审视以前的观察结果，并且随着输入的增长而变得不必要的昂贵。 Python 整数还可以避免执行减法时溢出的问题。 

有一些边界情况很容易处理不当。 如果只有一次观察，则没有之前的每日值，因此必须直接与初始量进行比较。 例如，```
10
7
```产生```
3
```从减去每日列表的相邻元素开始的粗心实现将根本不会产生任何答案。 

第一天的盗窃也可能比以后几天的盗窃更大。 例如，```
20
13 12 5
```产生```
7
1
7
```计算必须始终使用前一个金额，而不是假设盗窃金额是恒定的。 

最后，即使两个连续观测值碰巧相等，也应该执行算术。 例如，```
10
7 7 4
```产生```
3
0
3
```尽管最初的问题将数量描述为递减，但将输入视为连续观察可以使减法规则明确，并防止粗心的实现跳过相等的值。 

## 方法

 直接方法在这里已经是最佳方法。 暴力实现可以每天向后搜索之前的所有观察结果，以重建当天之前存在的糖果数量。 如果最终找到之前的金额，这仍然是正确的，但在最坏的情况下，它的表现可能约为`m(m-1)/2`比较`m`观测值，即`O(m²)`工作。 

输入的结构使得所有搜索都变得不必要。 计算今天的盗窃所需的唯一值是昨天剩余的糖果数量。 我们不需要完整的历史。 从原来的开始`n`，读取每个每日值`x`, 计算`previous - x`，输出差值，然后替换`previous`和`x`。 

暴力方法之所以有效，是因为可以从输入历史记录中恢复之前的金额，但它无法利用历史记录可以顺序处理的事实。 每个答案仅取决于前一个剩余金额的观察结果将问题简化为单遍。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(平方米) | O(米) | 对于大输入来说太慢 |
 | 最佳| O(米) | O(1) 辅助空间 | 已接受 |

 这里`m`是每日观察的数量。 

## 算法演练

 1. 读取罐子中糖果的初始数量并将其存储为`previous`。 这是必须与第一天的观察结果进行比较的金额。 
2. 阅读所有剩余的每日观察结果。 每个值代表当天被盗后剩余的糖果数量。 
3. 对于每个观测值`current`， 计算`previous - current`。 这正是两次观察之间移除的糖果数量。 
4. 将差异附加到输出并设置`previous = current`。 当日的剩余金额成为第二天所需的金额。 
5. 打印所有计算出的差异，每行一个。 按给定顺序处理观察结果可以保留减法所需的时间关系。 

### 为什么它有效

 不变量是在处理每日观察之前`current`,`previous`罐子里的糖果数量与当天失窃前罐子里的糖果数量完全相同。 对于第一个观察，这是正确的，因为`previous`从初始金额开始`n`。 处理一天后，分配`previous = current`使第二天的不变式成立。 由于一天被盗的数量恰好是被盗之前的金额减去被盗之后的金额，因此产生的每个差异都是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    remaining = list(map(int, sys.stdin.read().split()))

    previous = n
    answer = []

    for current in remaining:
        answer.append(str(previous - current))
        previous = current

    sys.stdout.write("\n".join(answer))

if __name__ == "__main__":
    solve()
```第一行初始化`previous`与原来数量的糖果。 输入的其余部分被读取`sys.stdin.read()`而不是在第二行假设特定数量的值。 这遵循问题将第二行描述为一系列观察的结果，同时也使解决方案对普通空白格式具有鲁棒性。 

该循环对每个观察值执行一次减法。 作业`previous = current`必须在计算差异后发生。 反转这两个操作将使每个减法都等于零。 

输出作为字符串累积并在最后写入一次。 这样就避免了重复调用`print`，当有很多观察值时这很有用。 Python 中不存在整数溢出问题。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(米) | 每个日常观察都被处理一次 |
 | 空间| O(米) | 该实现在写入之前存储观察结果和输出字符串 |

 计算本身仅使用`O(1)`辅助状态，即`previous`。 所提出的实现存储输入和输出，因为它将观察结果读取为完整的序列。 即便如此，它与输入大小是线性的。 由于该问题没有为观测数量提供明确的大范围，因此线性处理是适当的目标，并且避免了重复搜索历史的二次行为。

import sys
import io

def solve():
    n = int(input())
    remaining = list(map(int, sys.stdin.read().split()))

    previous = n
    answer = []

    for current in remaining:
        answer.append(str(previous - current))
        previous = current

    sys.stdout.write("\n".join(answer))

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    try:
        sys.stdin = io.StringIO(inp)
        input = sys.stdin.readline

        output = io.StringIO()
        old_stdout = sys.stdout
        sys.stdout = output

        try:
            solve()
        finally:
            sys.stdout = old_stdout

        return output.getvalue()
    finally:
        sys.stdin = old_stdin
        input = old_input

# Provided sample
assert run(
    "100\n"
    "97 92 85 80 72 65\n"
) == "3\n5\n7\n5\n8\n7", "sample 1"

# Minimum-size observation sequence
assert run(
    "10\n"
    "7\n"
) == "3", "single observation"

# All values equal, exercising a zero difference
assert run(
    "10\n"
    "7 7 4\n"
) == "3\n0\n3", "equal consecutive observations"

# Boundary-style decreasing sequence
assert run(
    "5\n"
    "4 3 2 1\n"
) == "1\n1\n1\n1", "consecutive one-candy thefts"

# Large input size
large = "100000\n" + " ".join(
    str(100000 - i) for i in range(1, 100000)
) + "\n"
expected = "\n".join(["1"] * 99999)
assert run(large) == expected, "large linear input"

 ## 边缘情况

 对于单个观察，例如```
10
7
```该算法开始于`previous = 10`，读取`current = 7`，并计算`10 - 7 = 3`。 然后它会更新`previous`到`7`并完成。 输出是`3`。 没有尝试访问较早的每日观察结果，因此不存在相差一的问题。 

对于不同的盗窃金额，请考虑```
20
13 12 5
```第一次迭代计算`20 - 13 = 7`，第二个计算`13 - 12 = 1`，第三个计算`12 - 5 = 7`。 输出是`7`,`1`,`7`。 该算法并不假设每天被盗的糖果数量相同。 

对于相等的连续观察，考虑```
10
7 7 4
```第一个区别是`10 - 7 = 3`。 然后状态变成`7`，所以第二个区别是`7 - 7 = 0`。 最后，状态变为`7`再次，最后一个区别是`7 - 4 = 3`。 输出是`3`,`0`,`3`。 顺序减法可以自然地处理这个问题，而不需要特殊情况。
