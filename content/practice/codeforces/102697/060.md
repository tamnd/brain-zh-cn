 ## 解决方案
 ## 问题理解

 该任务要求使用恰好 (N) 位可以表示的最大有符号整数。 对于有符号整数表示，为符号保留一位，为最大正值的大小保留 (N-1) 位。 因此最大值为

 [
 2^{N-1}-1。 
]

 输入由单个整数 (N) 组成，其中 (1 \le N \le 64)。 输出是相应的最大有符号整数。 官方问题陈述给出了相同的公式，并特别警告超过 32 位的值需要能够表示更大值的整数类型。 

约束故意很小，因为数学运算本身是常数时间。 尽管 (N) 可以达到 64，但我们永远不需要迭代可能的整数或模拟各个位。 与 (N) 成正比的算法已经足够了，而 (N) 中的任何指数都是不必要的，并且在 (N=64) 时变得不可能。 

主要的边缘情况来自最小位宽和大值。 对于(N=1)，只有一位符号位，没有大小位，因此最大可表示的有符号整数是(2^0-1=0)。 假设必须至少有一个幅度位的粗心实现可能会错误地产生 1。 

对于（N=2），答案是（2^1-1=1）。 完整的输入和输出是：```
2
```

```
1
```意外计算 (2^N-1) 的实现将返回 3，因为它将所有位视为幅度位并忽略带符号的表示。 

大（N）是另一种实际的边缘情况。 例如，对于 (N=64)，答案是

 [
 2^{63}-1=9223372036854775807。 
]

 使用浮点求幂可能会丢失整数精度，而使用固定宽度有符号 32 位整数会溢出。 Python的整数是任意精度的，因此直接整数表达式是安全的。 

## 方法

 最直接的暴力方法将生成用 (N) 位表示的每个有符号整数，测试它是否在表示的正范围内，并保留最大的整数。 (N) 位表示中有 (2^N) 个不同的位模式，因此在最坏的情况下需要 (O(2^N)) 个候选。 在 (N=64) 处，即 (2^{64}) 或大约 (1.84\times10^{19}) 次操作。 这种做法是完全行不通的。 

蛮力在概念上起作用，因为考虑了每种可能的表示，因此最终找到最大的有效正值。 问题在于，即使答案具有简单的数学形式，表示也具有大量的可能性。 

关键的观察是有符号整数使用一位作为符号。 要最大化正符号整数，符号位必须为零。 剩余的每个 (N-1) 位都应该是 1，因为将这些位中的任何一位从零更改为 1 都会增加值，同时保持符号为正。 因此，最佳位模式是 0 后跟 (N-1) 个 1。 

由 (N-1) 个 1 组成的二进制数的值为 (2^{N-1}-1)。 因此，我们不需要构建或检查任何候选编号。 一次求幂后进行一次减法可以直接给出答案。 

暴力搜索被所有正值按其大小位排序的观察所取代。 将每个可用的幅度位设置为 1 始终是最佳的，这可以将问题从指数枚举减少到恒定数量的算术运算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(2^N)) | (O(1)) | (O(1)) | 太慢了 |
 | 最佳 | (O(1)) | (O(1)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 读取位数 (N)。 输入仅包含一个值，因此不需要测试用例循环。 
2. 计算(2^{N-1})。 有 (N-1) 个幅度位，因为 (N) 位之一是符号位。 
3. 将结果减一。 (2^{N-1}-1) 正是由 (N-1) 个 1 组成的二进制数，它是可能的最大正值。 
4. 打印结果整数。 Python 的任意精度整数类型可以处理最大情况 (N=64) 而不会溢出。 

### 为什么它有效

 对于正符号 (N) 位整数，符号位固定为零。 其余（N-1）位贡献2的正幂，因此使它们中的任何一位等于1只能增加所表示的值。 当每个幅度位都是 1 时达到最大值。 生成的二进制值为 (1+2+4+\dots+2^{N-2})，等于 (2^{N-1}-1)。 因此，该算法始终准确地打印可用 (N) 位表示的最大有符号整数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
print((1 << (n - 1)) - 1)
```表达式`1 << (n - 1)`使用整数位移位计算 (2^{N-1})。 这完全避免了浮点运算，这很重要，因为浮点数无法准确表示每个大整数。 官方声明明确警告了该问题的浮点精度。 

移位后进行减法，与数学公式完全匹配。 该顺序很重要：`(1 << n) - 1`会错误地将所有 (N) 位视为幅度位并产生 (2^N-1)。 

Python 中不存在溢出问题，因为它的整数会自动增长到所需的大小。 在这个问题中，最大的中间值仅为 (2^{63})，这完全在 Python 的实际整数范围内。

def solve():

 ## 边缘情况

 对于 (N=1)，输入为：```
1
```该算法评估`(1 << 0) - 1`，给出 (1-1=0)。 没有幅度位，因此零确实是最大的有符号值。 输出是：```
0
```对于 (N=2)，输入为：```
2
```该算法计算`(1 << 1) - 1 = 2-1 = 1`。 可用的正表示是二进制的`01`， 尽管`11`在有符号补码解释下表示负值。 输出是：```
1
```对于最大值 (N=64)，输入为：```
64
```该算法计算 (2^{63}-1)，产生：```
9223372036854775807
```不会发生溢出，因为 Python 整数具有任意精度。 该计算还通过使用整数位移位来避免浮点精度问题。 

最常见的差一错误是使用 (2^N-1) 而不是 (2^{N-1}-1)。 例如，对于 (N=8)，错误的公式给出 255，但 8 位有符号整数只能表示最多 127 的正值。正确的计算使用 7 个大小位，给出 (2^7-1=127)。
