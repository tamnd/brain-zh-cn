 ## 解决方案
 ## 问题理解

 该字符串由小写字母和空格组成。 它的乐趣在于当前的角色数量`f`,`u`， 或者`n`。 我们可以对每个字母应用相同的循环凯撒移位任意多次。 移位将字母表中的每个字母向前移动一个位置，其中`z`环绕到`a`。 空间永远不会改变。 

任务是选择产生最多可能数量的班次`f`,`u`， 和`n`字符，然后打印最大计数。 官方问题使用 1 秒限制和 256 MB 内存。 

字母表仅包含 26 个字母，这是关键的结构限制。 可能有一个很长的输入字符串，因此为每个可能的移位构造一个新的移位字符串将重复扫描相同的数据。 每个角色只接触一次的解决方案是更好的选择。 固定字母表还意味着，在按 26 个字母频率汇总输入后，尝试每种可能的转变只需花费恒定的工作量。 

有几种小情况可能会欺骗实现。 首先，概括在`z`很重要。 对于输入`z`，一班给出`a`，而六班倒给`f`，所以正确答案是`1`。 简单地添加移位而不取模 26 的实现将无法认识到这一点。 

其次，空格不得对分数产生影响，也不得被视为字母。 例如，`a a`有两个字母和一个空格。 正确的实现可以将两个字母放在一起并获得最大的乐趣`2`。 将空格视为另一个字母字符会破坏频率计算。 

第三，三个目标字母在字母表中不相邻。 例如，`fun`本身就已经有乐趣了`3`，因此零移是最佳的。 假设目标字符形成一个连续间隔的实现将使用错误的条件。 

第四，相同的移位适用于整个字符串。 为了`fu`，两个字符可以同时成为带有移位零的目标字符，给出`2`。 为每个角色选择不同的班次是无效的。 这样做会错误地使几乎每个字母都独立计数。 

## 方法

 最直接的方法是尝试每一种可能的循环移位。 只有 26 个不同的移位，因为应用移位 26 次会将每个字母返回到其原始值。 对于每次移位，我们可以扫描整个字符串，将每个字母转换为其移位后的值，如果结果为，则对其进行计数`f`,`u`， 或者`n`。 这是正确的，因为每个可能的最终字符串都由这 26 个移位之一表示。 

对于一个长度的字符串`n`，蛮力实现的执行效果完全一样`26n`字符访问，忽略计算每个移位字符所需的较小常数工作。 例如，具有 100 万个字符的字符串会导致大约 2600 万个字符检查。 渐进复杂度仍然是`O(n)`因为 26 是一个固定常量，所以这种方法可能会通过，但它会执行相同的昂贵扫描 26 次。 

有用的观察是字符的位置根本不重要。 只有每个字母出现的次数才重要。 假设原始字符串包含`cnt[c]`信件副本`c`。 对于选定的班次`k`，这些副本中的每一个都变成相同的移位字母`(c + k) mod 26`。 因此，我们可以直接从 26 个频率计数中计算出该转变的分数。 

对字符串进行一次扫描后，我们就获得了评估每个班次所需的所有信息。 对于 26 个班次中的每个班次，我们只需要检查将变成的三个原始字母`f`,`u`， 和`n`。 无论输入的长度如何，最多 78 次频率查找。 

当字符串很长时，差异很显着。 暴力版本重复处理原始文本，而优化版本将整个文本压缩为 26 个计数器，然后完全在这些计数器上工作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(26n) = O(n) | O(1) | O(1) | 以渐近方式接受，但不必要地重复扫描 |
 | 最佳 | O(n + 26 × 3) = O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取整个输入行，包括空格，因为空格是字符串的一部分，但必须保持不变。 
2. 创建数组`cnt`长度为 26。对于输入中的每个小写字母，递增与其字母表索引相对应的计数器。 忽略空格，因为它们永远不会成为`f`,`u`， 或者`n`。 
3. 尝试每个班次`k`从`0`通过`25`。 这些都是可能的不同最终配置，因为 26 的移位与 0 的移位相同。 
4. 对于当前班次`k`，确定哪些原始字母变成`f`,`u`， 和`n`。 如果目标字母有索引`t`，其原字母必须有索引`(t - k) mod 26`。 因此，该转变的分数是以下总和`cnt[(5 - k) mod 26]`,`cnt[(20 - k) mod 26]`， 和`cnt[(13 - k) mod 26]`， 在哪里`f`,`u`， 和`n`具有索引 5、20 和 13。 
5. 保留所有 26 个班次中遇到的最大分数并将其打印。 由于已经检查了每种可能的循环移位，因此最大记录值正是可实现的最大乐趣。 

### 为什么它有效

 不变的是`cnt[c]`始终精确地表示带索引的字母有多少个原始字符`c`。 对于固定班次`k`, 一封原信`c`变成`(c + k) mod 26`。 当该值为 5、20 或 13 时，它会增加乐趣。反转该关系可得出三个原始索引`(5-k) mod 26`,`(20-k) mod 26`， 和`(13-k) mod 26`。 因此，每个班次的计算分数准确地计算了成为的字符`f`,`u`， 或者`n`。 由于所有 26 个可能的班次都经过测试，因此取最大值不会错过更好的结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().rstrip('\n')

    cnt = [0] * 26

    for ch in s:
        if ch != ' ':
            cnt[ord(ch) - ord('a')] += 1

    targets = (ord('f') - ord('a'),
               ord('u') - ord('a'),
               ord('n') - ord('a'))

    ans = 0

    for shift in range(26):
        score = 0
        for target in targets:
            original = (target - shift) % 26
            score += cnt[original]
        ans = max(ans, score)

    print(ans)

if __name__ == "__main__":
    solve()
```第一个循环构建频率表。`ord(ch) - ord('a')`皈依者`a`通过`z`转化为指数`0`通过`25`。 空格的条件是必要的，因为输入行可以包含空格，而空格不是循环字母表的一部分。 

这`targets`元组存储定义乐趣的三个字母。 对于每一个可能的转变，代码都会从每个目标向后查找将成为该目标的原始字母。 模运算可以正确处理环绕。 例如，如果目标是`f`移位为7，所需原始索引为`(5 - 7) % 26 = 24`，即`y`。 确实，转移`y`七个位置给出`f`。 

无需构造移位字符串。 频率数组已经包含有关每个字母存在多少个副本的所有信息。 Python整数在这里也没有固定宽度溢出问题，答案最多是输入中的字符数。 

使用`rstrip('\n')`而不是`strip()`是故意的。`strip()`将从输入中删除前导和尾随空格，而空格是字符串中的有效字符。 单独删除换行符会保留实际的输入文本。

import sys
import io

def solve():
    s = sys.stdin.readline().rstrip('\n')

    cnt = [0] * 26

    for ch in s:
        if ch != ' ':
            cnt[ord(ch) - ord('a')] += 1

    targets = (5, 20, 13)
    ans = 0

    for shift in range(26):
        score = 0
        for target in targets:
            score += cnt[(target - shift) % 26]
        ans = max(ans, score)

    print(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("hello world\n") == "5\n", "sample 1"
assert run("coderams contest number eight\n") == "9\n", "sample 2"

# Minimum-size input
assert run("a\n") == "1\n", "single letter"

# All characters equal
assert run("aaaa\n") == "4\n", "all equal"

# Wraparound at z: shifting z by 6 gives f
assert run("zzz\n") == "3\n", "z wraparound"

# Spaces must not affect the count
assert run("a a a\n") == "3\n", "spaces"

# Large input
assert run("a" * 100000 + "\n") == "100000\n", "large input"

 ## 边缘情况

 对于环绕式情况，请考虑`zzz`。 每轮 6 张地图`z`到`f`，所以答案是`3`。 频率表包含`cnt[25] = 3`。 当算法检查班次 6 和目标时`f`，它计算`(5 - 6) % 26 = 25`，检索所有三个副本`z`，并获得 3 分。模运算使字母表呈圆形而不是线性。 

对于空间，请考虑`a a a`。 输入包含三个字母和两个空格。 换档每`a`5 将所有三个字母变成`f`，所以答案是`3`。 频率表存储`cnt[0] = 3`没有任何空间。 当检查第 5 班时，原来的字母变成`f`是`(5 - 5) % 26 = 0`，因此所有三个事件都被计数。 

对于已经最优的输入，请考虑`fun`。 使用shift 0，所有三个字符都已经在目标字母中，所以答案是`3`。 频率表包含以下各出现一次`f`,`u`， 和`n`，并且零移位计算精确读取这三个计数器。 不同的班次可能会将它们移动到其他地方，但最多仍为 3 个。 

对于单个字符，例如`a`，总是存在将其映射到目标字母之一的转变。 变速`a`5 给出`f`，所以算法返回`1`。 这也证实了答案是基于在一次常见转换下可以变得有趣的字符数量，而不是基于字符串的原始有趣性。 

关键的边界条件是只需要考虑 26 个班次。 Shift 0 使字符串保持不变，而shift 25 相当于将每个字符向后移动一位。 假设的移位 26 将返回到原始字符串，因此测试它不会增加新的可能性。
