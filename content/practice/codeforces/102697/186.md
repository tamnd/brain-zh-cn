 ## 解决方案
 ## 问题理解

 输入是一行，包含无线电消息的嘈杂转录。 普通字符属于原始消息。 每一段无线电静电都用下划线括起来，因此形式的子字符串`_static_`必须完全删除，包括两个下划线。 这些区域之外的字符构成了答案。 

例如，在`hello_***_hello`, 中间`***`是静态的，所以恢复的消息是`hellohello`。 在`code ram_^_s^^^`, 子串`^`两个下划线之间的字符是静态的，而其周围的空格和字母是消息的一部分。 

该语句没有给出行长度的单独数字界限，因此有用的约束只是输入可能足够长，以至于我们应该只处理每个字符恒定的次数。 O(L) 算法（其中 L 是行长度）是最佳的，因为即使读取输入也已花费 O(L)。 随着转录的增长，O(L²) 解决方案可能会变得太慢。 

在一些边界情况下，实现通常会出错。 一行可以以 static 开头，如`_abc_code`，其正确输出是`code`。 假设第一个字符始终是消息的一部分的粗心解决方案将错误地保留`abc`。 一行可以在静态之后立即结束，如`code_abc_`，其输出是`code`; 在关闭静态区域之前等待另一个普通字符的实现可能会错误地处理最后的下划线。 多个静态区域也可以相邻，如`a_x__y_b`，其中静态部分之间的两个下划线是单独的分隔符，结果是`ab`。 最后，一行可以包含空格，它们是真正的消息字符，如`_noise_hello world_noise_`，其输出是`hello world`。 对空白进行分割会破坏这些空间。 

## 方法

 一种直接但低效的方法是重复搜索第一个下划线，搜索下一个下划线，并从当前字符串中物理删除整个静态区域。 这在逻辑上是正确的，因为每个静态区域正是一对下划线之间的文本。 问题是重复的字符串修改。 如果输入的长度为 L 并且包含 θ(L) 个小静态区域，则每次删除可以复制 θ(L) 个字符，在最坏的情况下给出 θ(L²) 个字符操作。 例如，包含许多交替的普通字符和单字符静态区域的行可以强制实现重复重建几乎整个剩余字符串。 

输入的结构为我们提供了更简单的观察。 从左到右扫描时，下划线告诉我们是进入还是离开静态。 在静态之外，每个字符都属于答案。 在 static 内部，每个字符都应该被忽略。 由于只有遇到下划线时状态才会改变，因此一个布尔变量足以描述我们需要知道的一切。 

暴力方法之所以有效，是因为它识别完全相同的下划线分隔区域，但它会重复修改已处理的数据。 通过观察静态由简单的交替状态表示，我们可以处理一次转录，仅附加在静态之外看到的字符，并在线性时间内完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 |---|---|---|---|
 | 蛮力 | O(L²) | O(L) | 太慢了|
 | 最佳| O(L) | O(L) | 已接受 |

 ## 算法演练

 1. 阅读整行，不要删除中间的空格。 输入代表一条消息，而不是空格分隔的标记列表，因此`input()`而不是`split()`是适当的操作。 

2. 开始于`inside_static = False`。 在看到任何下划线之前，字符属于原始消息。 

3. 从左到右扫描每个字符。 如果字符是下划线，则切换`inside_static`。 下划线是分隔符，因此永远不会将其复制到答案中。 

4. 如果该字符不是下划线并且`inside_static`为 false，将其附加到结果中。 这样的字符是外部静态的并且是恢复的消息的一部分。 

5. 如果该字符不是下划线且`inside_static`是真的，丢弃它。 静态区域内的每个字符都是噪声。 

6. 扫描结束后，打印累计结果。 定界符结构保证每个静态部分在其开始和结束下划线之间被精确地跳过。 

关键的不变量是在处理每个字符之前，`inside_static`is true exactly when the current position lies inside a static region. An underscore changes that state because it is precisely a boundary between message and static. 因此，每个非下划线字符都在属于原始消息的时候准确地附加，并且每个静态字符在应该被丢弃的时候被准确地丢弃。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().rstrip('\n')

    inside_static = False
    ans = []

    for ch in s:
        if ch == '_':
            inside_static = not inside_static
        elif not inside_static:
            ans.append(ch)

    print(''.join(ans))

if __name__ == "__main__":
    solve()
```致电给`rstrip('\n')`仅删除行终止符。 它故意不使用`strip()`，因为前导或尾随空格可以是有意义的消息字符。 

这`inside_static`标志直接对应于算法演练中的状态。 每个下划线都会切换它，因此第一个下划线进入静态，下一个下划线离开静态。 这也可以处理以 static 开头或结尾的输入，而不需要特殊情况。 

结果存储在列表中，而不是重复连接字符串。 Python字符串是不可变的，所以会重复`ans += ch`可能会引入不必要的复制。 将字符追加到列表中的时间为常数摊销时间，并且`''.join(ans)`构造一次最终的字符串。 

没有整数运算，因此溢出是无关紧要的。 该循环对每个输入字符处理一次，唯一的边界条件是下划线切换，这完全避免了索引计算。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 |---|---|---|
 | 时间 | O(L) | 每个字符都被检查一次，最后的结果`join`与输出大小呈线性关系。 |
 | 空间| O(L) | 结果列表为每个非静态字符最多存储一个条目。 |

 由于读取 L 字符输入已经需要 O(L) 工作，因此线性扫描是渐近最优的。 该算法还避免了重复复制剩余的转录，因此其运行时间与实际输入大小成比例增长。

import sys
import io

def solve():
    s = sys.stdin.readline().rstrip('\n')

    inside_static = False
    ans = []

    for ch in s:
        if ch == '_':
            inside_static = not inside_static
        elif not inside_static:
            ans.append(ch)

    print(''.join(ans))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample 1
assert run(
    "hellowor_*%^&&^%&^&%*_ldcoder_%^%^_ams\n"
) == "helloworldcoderams\n", "sample 1"

# Provided sample 2
assert run(
    "hello_***_hello\n"
) == "hellohello\n", "sample 2"

# Provided sample 3
assert run(
    "_^*&^^&**&^*^&*&^*^&_code ram_^_s^^^\n"
) == "code rams^^^\n", "sample 3"

# Minimum-size message
assert run("a\n") == "a\n", "single ordinary character"

# All characters are static
assert run("_abc_\n") == "\n", "everything is static"

# Consecutive static regions and empty message portions
assert run("a_x__y_b\n") == "ab\n", "adjacent static regions"

assert run("_noise_hello world_noise_\n") == "hello world\n", "boundary static regions"

# Spaces inside the actual message

 ## 边缘情况

 当输入以静态开始时，状态机立即处理边界。 为了`_abc_code`，第一个下划线变化`inside_static`从假到真，`abc`被丢弃，第二个下划线将状态更改回 false。 人物`code`然后附加，给出`code`。 字符串开头不需要特殊情况。 

当输入在静态后结束时，结束下划线仍会在扫描完成之前切换状态。 为了`code_abc_`,`code`已附加，`abc`被忽略，最后的下划线将状态返回到 false。 答案正是`code`。 不需要检查结束定界符之后的字符，因此避免了基于相邻索引的实现。 

对于连续的静态区域，考虑`a_x__y_b`。 第一个下划线进入静态，下一个离开它，后面的下划线立即再次进入静态，最后一个相关下划线离开它。 人物`x`和`y`都被丢弃，同时`a`和`b`被保留。 结果是`ab`。 切换模型自然会处理两个分隔符之间的空消息段。 

空格必须被视为普通字符，除非它们位于 static 内部。 在`_noise_hello world_noise_`，第一个噪声区域被丢弃，两个单词及其分隔空间被附加，最后一个噪声区域被丢弃。 输出是`hello world`。 这就是程序读取整行而不是将其拆分为空格分隔的标记的原因。 

同样的方法还可以处理根本不包含下划线的输入。 为了`hello world`，在整个扫描过程中状态保持为 false，因此每个字符都会被复制并且输出与输入相同。 这是最简单的不变量情况，扫描仪永远不会进入静态。
