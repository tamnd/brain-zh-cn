 ## 解决方案
 ## 问题理解

 任务是执行一种小型的自定义编程语言。 输入描述了一系列源代码行，我们的程序必须表现得好像这些行是按顺序执行的。 该语言具有三种语句：变量声明、赋值和打印。 声明或赋值计算整数表达式，而 print 语句将文字文本与变量的当前值组合起来。 官方声明指定了语法并给出了下面使用的示例执行。 

声明的形式为`var name = expression`，而作业的形式为`name = expression`。 表达式包含整数常量、先前定义的变量、加法和减法。 例如，之后`var a = 5`，声明`a = a - 1`变化`a`到`4`。 

print 语句与普通算术语法略有不同。 文本出现在括号内，例如`(hello world)`，而要打印的变量出现在两个加号之间，例如`+a+`。 这些片段完全按照它们出现的样子连接起来。 一条打印语句完成一个输出行。 

第一个输入行告诉我们后面有多少源代码行。 剩下的几行是程序本身。 我们的输出正是按顺序执行这些源代码行所产生的文本。 官方限制是一秒的时间限制和 256 MB 的内存，尽管该声明没有公开源代码行数或其长度的单独数字上限。 因此，正确的目标是源代码总量中的线性时间。 重复扫描所有先前代码或重复重建大型字符串的算法可能会变得不必要的昂贵。 字典查找和每行一次扫描就足够了。 

在一些小情况下，实现可能会默默地出错。 考虑```
1
print (hello)
```正确的输出是```
hello
```期望每个打印语句都包含变量的解析器在这里会失败。 

另一种情况是```
4
var a = 5
var b = a - 2
a = b + 10
print +a+( )+b+
```正确的输出是```
13 3
```粗心的实现可能会存储`b`作为表达式文本而不是立即对其求值，或者可能使用旧值`a`任务完成后。 

文字内的间距是另一个重要的细节。 在```
1
print (hello   world)
```输出是```
hello   world
```这三个空格是文字的一部分，不能与`split()`。 

最后，打印语句可以混合多种类型的语句：```
4
var x = 7
var y = 2
var z = x - y
print +x+( - )+y+( = )+z+
```输出是```
7 - 2 = 5
```简单地用空格分割整行的解析器失去了文字文本和变量替换之间的区别。 

## 方法

 最直接的暴力实现将每个表达式视为字符串，并重复搜索它以将变量名称替换为其当前值。 替换后，它计算算术表达式。 这是正确的，因为每个变量的出现最终都会成为存储在字典中的值，因此生成的算术表达式与原始算术表达式具有相同的值。 

问题就出在重复寻找上。 假设一个表达式有长度`L`并且有`V`变量。 如果通过扫描表达式来搜索和替换每个变量，则一条语句可以采用`O(LV)`时间。 和`V`和`L`两者都与输入的大小成正比，这可以变成二次方。 包含大约的源文件`10^5`相关令牌可能需要按以下顺序`10^10`字符操作，远远超出了一秒的极限所能容忍的。 

暴力方法之所以有效，是因为变量替换最终为我们提供了一个正常的算术表达式，但它失败了，因为它执行了语法不需要的工作。 关键的观察是表达式已经由小的独立部分组成，即整数文字、变量名称和运算符。 当我们扫描表达式时，我们可以直接从字典中解析每个操作数。 没有理由每次出现变量时都在整个程序中搜索它。 

同样的想法也适用于印刷。 打印行已被其分隔符分为文字文本块和变量块。 我们可以扫描一次，直接复制文字文本，并对每个变量执行一次字典查找。 因此，每个源字符仅被处理固定次数。 

对于算术评估，该语句使用加法和减法描述简单的方程。 提供当前变量作为评估环境后，我们就可以使用Python的算术评估器。 输入是受控的竞赛语言表达式，而不是任意的 Python 代码，并且在禁用内置函数的情况下调用评估器。 这使实现保持紧凑，同时保留小型表达语言的预期语义。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 最坏情况下的 O(LV) | O(L + V) | 太慢了 |
 | 最佳 | O(L) 表示源总长度 | O(V + L) | 已接受 |

 这里`L`表示源程序中的字符总数，`V`表示存储变量的数量。 

## 算法演练

 1.读取源代码行数并创建一个空字典`variables`。 该字典表示模拟程序的当前状态，因此在处理源的任何前缀后，每个定义的变量都准确映射到其当前的整数值。 
2. 从上到下处理每个源代码行。 执行顺序很重要，因为表达式可能依赖于先前语句建立的值。 
3. 如果该行开头为`var `，首先拆分声明`=`。 左边的文本给出了变量名称，右边的​​文本是它的表达式。 使用当前字典计算表达式并将结果整数存储在该名称下。 
4. 否则，如果该行是一个赋值行，则在第一个行将其拆分`=`。 使用赋值之前存在的值计算右侧表达式，然后用新结果替换左侧变量的旧值。 在更新字典之前评估完整的右侧可以避免意外使用部分修改的状态。 
5. 否则该行是一条打印语句。 之后立即开始扫描`print `。 当下一个字符是`(`，找到匹配的`)`并将它们之间的所有内容附加到输出中。 内容是文字文本，因此空格和标点符号必须原封不动地复制。 
6. 当下一个字符是`+`，找到以下内容`+`。 这两个分隔符之间的文本是变量名称。 查找它在`variables`，将整数转换为字符串，并将其附加到当前输出行。 
7. 继续，直到消耗完完整的打印语句。 在生成的输出中添加换行符并处理下一个源代码行。 
8. 执行完所有源代码行后，将累积输出写入一次。 累积字符串并写入一次可以避免为每个打印语句进行单独的系统输出调用。 

关键的不变量是在处理每个源代码行之前，`variables[name]`等于模拟伪代码程序分配给的值`name`在所有前面的行之后。 声明和赋值保留了这种不变性，因为它们的右侧是使用当前状态计算的，然后存储结果值。 Print 语句不会修改字典，因此它们也会保留它。 由于每个变量替换都准确读取当前值，因此每个生成的输出行都与模拟程序生成的行相同。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def evaluate(expr, variables):
    # The problem's expressions use integer constants, variables,
    # addition, and subtraction.
    return eval(expr, {"__builtins__": {}}, variables)

def solve():
    n = int(input())
    variables = {}
    output = []

    for _ in range(n):
        line = input().rstrip('\n')

        if line.startswith("var "):
            name, expr = line[4:].split("=", 1)
            name = name.strip()
            variables[name] = evaluate(expr.strip(), variables)

        elif line.startswith("print"):
            pos = 5

            # The syntax in the statement has a space after "print".
            if pos < len(line) and line[pos] == ' ':
                pos += 1

            current = []

            while pos < len(line):
                if line[pos] == '(':
                    end = line.find(')', pos + 1)
                    current.append(line[pos + 1:end])
                    pos = end + 1

                elif line[pos] == '+':
                    end = line.find('+', pos + 1)
                    name = line[pos + 1:end]
                    current.append(str(variables[name]))
                    pos = end + 1

                else:
                    # The grammar normally has delimiters immediately
                    # after "print", but skip harmless separator spaces.
                    pos += 1

            output.append(''.join(current))

        else:
            name, expr = line.split("=", 1)
            name = name.strip()
            variables[name] = evaluate(expr.strip(), variables)

    sys.stdout.write('\n'.join(output))

if __name__ == "__main__":
    solve()
```这`variables`字典是伪代码程序的模拟内存。 声明和赋值仅在关键字和变量是否已存在方面有所不同，因此两者最终都会执行相同的字典更新。 

表达式被传递到`evaluate`仅当该语句与其左侧分离后。 第一个`=`用于分割，因为整个余数属于表达式。 呼唤`split("=", 1)`防止以后发生`=`意外更改解析边界。 

打印解析器故意不调用`split()`就行了。 文字文本可以包含空格，这些空格是所需输出的一部分。 相反，解析器从一个分隔符移动到另一个分隔符。 括号标识文字文本，而成对的加号标识变量名称。 

这`find`调用也受当前打印行的限制。 每对分隔符都通过移动而消耗`pos`超出其结束分隔符，因此从左到右扫描打印行，而不是从头开始重复重新扫描。 

Python 整数具有任意精度，因此即使测试数据包含大于固定宽度 C++ 整数的值，算术值也不会溢出。 决赛`join`还避免了不必要的尾随换行符。 对于没有 print 语句的程序，`output`保持为空并且程序写入一个空字符串。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 预期 O(L) | 每个源字符都会被处理固定次数，字典操作的时间复杂度预计为 O(1)。 |
 | 空间| O(L) | 字典存储变量名称和值，而输出和当前源代码行占用的空间与输入和生成的输出成比例。 |

 这里`L`是源程序中的字符总数。 由于官方时间限制为一秒，并且问题在显示的语句页面上没有给出明确的数值源大小限制，因此线性处理是自然的目标。 该实现不会构建整个程序的中间副本，也不会通过旧源代码行重复替换变量，因此其工作量直接随输入量而扩展。

 ## 边缘情况

 仅包含文字的打印语句通过输入`(`立即分支并将文本附加到括号之间。 为了```
1
print (hello)
```扫描仪读取`hello`并产生`hello`。 不会尝试字典查找，因此缺少变量是无害的。 

可以使用另一个变量的当前值来分配一个变量。 为了```
4
var a = 5
var b = a - 2
a = b + 10
print +a+( )+b+
```字典从`{a: 5}`到`{a: 5, b: 3}`，然后到`{a: 13, b: 3}`。 最终输出是`13 3`。 分配给`a`仅在评估其整个右侧后才会发生。 

保留文字空格是因为打印解析器提取之间的子字符串`(`和`)`直接地。 和```
1
print (hello   world)
```子字符串包含三个空格，因此输出也包含三个空格。 将 print 语句标记为`split()`会错误地丢弃该信息。 

负的中间结果是普通整数值。 为了```
5
var a = 2
var b = a - 9
a = b + 4
var c = a - b
print +a+( )+b+( )+c+
```值变成`a = 2`， 然后`b = -7`， 然后`a = -3`，最后`c = 4`。 生成的输出是`-3 -7 4`。 Python 的整数表示还避免了在表达式值变大时固定宽度实现可能出现的溢出问题。 

print 语句可以任意交替文字和变量片段。 为了```
4
var x = 7
var y = 2
var z = x - y
print +x+( - )+y+( = )+z+
```扫描仪读取变量`x`，那么字面量`-`， 然后`y`， 然后`=`， 然后`z`。 结果行是`7 - 2 = 5`。 解析器从不将括号内的空格视为语法，这正是自定义语言所要求的。 

最后的边缘情况是没有打印语句的程序。 例如，```
3
var a = 10
a = a - 3
var b = a + 2
```不产生输出。 模拟器仍然执行每个赋值，因为后面的语句可能依赖于这些值，但输出列表仍然为空，并且不会写入任何内容。
