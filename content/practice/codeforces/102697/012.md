 ## 解决方案
 ## 问题理解

 任务是计算一个小的幂。 输入包含两个整数，`n`和`k`，代表底数和指数。 输出应该是精确值`n`提升到的权力`k`，而不仅仅是数字或简化形式。 约束条件故意很小：两个值都最多为 10，因此最大可能的答案仅为`10^10`，它很容易适合常见的整数类型。 原始问题陈述确认了直接计算是预期的，因为这里暴力方法就足够了。 

由于数字非常小，因此不需要先进的求幂技术、模算术或对巨大值的特殊处理。 即使将基数乘以自身十次的循环也仅执行恒定数量的操作。 任何具有多项式或对数复杂度的算法也可以通过，但它会解决比实际给出的问题更难的问题。 

主要的边缘情况来自正确处理指数。 如果指数为零，则数学结果为一，但此输入范围从一开始，因此不会出现这种情况。 最小的有效输入是一的底数和指数。 例如：```
Input:
1 1

Output:
1
```粗心的实现会错误地初始化答案，例如从零开始，会输出零，因为每次乘法都会保留该错误。 

另一个可能的错误是颠倒两个数字的含义。 第一个值是底数，第二个值是指数。 例如：```
Input:
2 3

Output:
8
```计算`3^2`相反会产生`9`，这是错误的。 

## 方法

 最简单的方法是模拟求幂的定义。 从等于 1 的答案开始，将其精确乘以基数`k`次。 这有效是因为`n^k`定义为`n * n * ... * n`和`k`的副本`n`。 由于最大指数只有十，因此最多需要十次乘法。 

更通用的方法是二进制求幂，它通过重复对底数进行平方来减少非常大指数的乘法次数。 然而，当前的问题不需要这种优化。 添加它会使代码变得更长，而不会在这些限制下改进解决方案。 

蛮力法之所以有效，是因为指数受一个非常小的常数限制。 如果指数可以大到`10^18`，重复乘法是不可能的，而需要对数方法。 在这里，输入的结构消除了这种需要。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(k) | O(1) | O(1) | 已接受 |
 | 最佳| O(k) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读基础`n`和指数`k`从输入。 第一个数字控制乘法的内容，第二个数字控制乘法发生的次数。 
2. 将答案初始化为`1`。 这是乘法的中性值，因此第一个乘法产生正确的部分结果。 
3. 重复`k`次，将当前答案乘以`n`每次迭代后。 第一次迭代后的值为`n`，第二个之后是`n^2`，最后一次迭代后，它变成`n^k`。 
4. 打印最终值。 

为什么它有效：在每个乘法步骤之后，答案准确地存储由已完成的迭代次数表示的幂。 循环完全执行`k`乘法，所以当它完成时，存储的值是精确的`n^k`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    ans = 1
    for _ in range(k):
        ans *= n

    print(ans)

if __name__ == "__main__":
    solve()
```输入被直接读取为整数，因为约束保证两个值正常拟合。 变量`ans`从 1 开始，因为乘以 1 不会改变结果，这为构建幂提供了正确的起点。 

循环使用`range(k)`所以确切地说`k`乘法发生。 这里很容易犯一个相差一的错误：使用`range(k + 1)`会计算`n^(k+1)`，虽然使用较少的迭代会错过一个因素`n`。 

Python 整数在必要时会自动增长，因此不存在溢出问题。 尽管这里的最大答案很小，但使用普通的整数算术就足够了。 

## 工作示例

 对于输入：```
3 5
```执行是：

 | 迭代| 当前答案 | 运营|
 | --- | --- | --- |
 | 开始| 1 | 初始值|
 | 1 | 3 |`1 * 3`|
 | 2 | 9 |`3 * 3`|
 | 3 | 27 | 27`9 * 3`|
 | 4 | 81 | 81`27 * 3`|
 | 5 | 243 | 243`81 * 3`|

 最终值为`243`，即`3^5`。 该迹线表明每次迭代恰好添加了基数的一个因子。 

对于输入：```
10 3
```执行是：

 | 迭代| 当前答案 | 运营|
 | --- | --- | --- |
 | 开始| 1 | 初始值|
 | 1 | 10 | 10`1 * 10`|
 | 2 | 100 | 100`10 * 10`|
 | 3 | 1000 | 1000`100 * 10`|

 最终值为`1000`，证明该算法可以处理更大的基数，而无需任何特殊情况。

## 测试用例```python
import sys
import io

def solution(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n, k = map(int, sys.stdin.readline().split())
    ans = 1
    for _ in range(k):
        ans *= n

    sys.stdin = old_stdin
    return str(ans)

# provided sample
assert solution("3 5\n") == "243", "sample 1"

# minimum values
assert solution("1 1\n") == "1", "minimum input"

# base equal to maximum value
assert solution("10 10\n") == "10000000000", "maximum input"

# same values
assert solution("5 5\n") == "3125", "all equal values"

# boundary where reversing base and exponent changes result
assert solution("2 10\n") == "1024", "base exponent order"

 ## 边缘情况

 对于尽可能最小的输入：```
1 1
```该算法开始于`ans = 1`，执行一次乘法，得到`1`。 这证实了初始化不会意外引入零结果。 

对于两个数字的顺序很重要的情况：```
2 3
```循环乘以`2`三次：```
1 -> 2 -> 4 -> 8
```输出是`8`。 将第一个数字视为指数的错误实现`3^2`并在这个案例中失败。 

对于最大允许输入：```
10 10
```循环执行十次乘法并达到`10000000000`。 该算法不需要特殊处理，因为 Python 整数可以准确表示结果。
