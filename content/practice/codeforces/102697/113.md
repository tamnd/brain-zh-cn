 ## 解决方案
 ## 问题理解

 您正飞往几个机场之一。 每个机场都有许多可用的跑道空间、距您当前位置的距离以及飞机必须飞行才能到达的方向。 您还知道剩余的燃料量（以您正常飞行的最大英里数表示）以及当前的风向。 

机场只有在至少有一条可用跑道空间并且可以用剩余燃料完成飞行时才可以使用。 风改变了有效的燃料成本。 当所需飞行方向与风向相同时，燃油消耗减半，因此飞行距离为`d`成本`d / 2`燃料单位。 当飞机直接逆风飞行时，消耗加倍，所以同样的距离花费`2d`。 对于其余方向，使用正常距离。 

在可用的机场中，所需的选择是最接近的机场。 问题陈述没有提供明确的数字约束，但限制是一秒，输入是简单的机场列表。 自然的解决方案是单次扫描，需要每个机场持续不断的工作。 即使机场数量多到`10^5`或者`10^6`， 一个`O(n)`扫描无疑是预期的方法，而尝试每一对机场或重复排序会增加不必要的工作。 

风计算是造成错误的主要原因。 距离本身不会改变，改变的只是行驶距离所需的燃料量。 尽管顺风使旅行更便宜，但很容易错误地拒绝机场，因为其物理距离大于剩余燃料。 

例如，考虑：```
2
20
S
1 20 S
1 20 N
```第一个机场要求向南飞行，完全顺风。 其有效燃料成本为`20 / 2 = 10`，所以是可达的。 第二个机场需要向北飞行，逆风，所以它的成本是`20 * 2 = 40`，使其无法访问。 正确的输出是`1`。 如果粗心地比较原始距离而不考虑风力，则会错误地将两个机场视为同等可达。 

另一个边界情况是机场的调整成本恰好是可用燃料。 如果飞机能飞`20`里程和机场费用完全一样`20`，该机场可达。 比较必须是`cost <= fuel`， 不是`cost < fuel`。 

第二个常见错误是接受可用跑道空间为零的机场。 例如：```
1
100
N
0 10 N
```机场足够近，但是没有地方可以降落，所以不能选择。 正确的实现必须在考虑其距离之前拒绝它。 

## 方法

 思考该问题的强力方法是生成每种可能的机场选择，计算该机场是否可达，并将其与所有其他候选机场进行比较，以确定哪个机场最接近。 这是正确的，因为每个机场都被明确检查，但成对比较是不必要的。 和`n`机场，比较每对需要`n(n - 1) / 2`比较，这大约是`5 * 10^9`比较时`n = 100000`。 这远远超出了一秒钟竞赛程序的处理能力。 

有用的观察结果是机场是独立的。 是否机场`i`其可达性仅取决于其自身的跑道数量、其自身的距离、其方向和全球风向。 机场之间没有互动。 一旦机场被转换成其有效燃料成本，我们只需要维护迄今为止看到的最佳候选机场。 

这将问题变成了简单的扫描。 对于每个机场，如果没有跑道空间，首先拒绝。 然后根据机场和风的相对方向计算其有效燃油成本。 如果成本超过可用燃料，则拒绝它。 否则，将其物理距离与迄今为止找到的最近的有效机场进行比较。 由于每个机场仅被考虑一次，因此最终存储的索引就是所需的答案。 

无需浮点运算也可以进行风力调整。 对于顺风，条件`d / 2 <= fuel`相当于`d <= 2 * fuel`。 对于逆风，条件`2 * d <= fuel`可以直接检查。 对于中性方向，条件很简单`d <= fuel`。 使用整数比较可以避免精度问题`d`很奇怪。 

官方声明给出了 1 秒的时间限制和 256 MB 的内存限制，但没有指定机场数量的明确数字限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 对于大 n 来说太慢 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取机场数量、可用燃料和风向。 在检查每个机场时，这些值保持固定。 
2. 将最佳机场初始化为不存在，将最佳距离初始化为无穷大。 这使得第一个有效机场自动成为当前候选机场，而无需特殊情况。 
3. 了解每个机场的跑道可用性、实际距离和所需的飞行方向。 如果跑道数为零，请立即丢弃，因为无论燃料如何，机场都无法使用。 
4. 确定风的燃料倍数。 如果所需方向等于风向，则有效成本为`d / 2`。 如果要求的方向是相反方向，则成本为`2d`。 否则，成本是`d`。 
5. 测试剩余燃油是否可以到达机场。 使用整数不等式而不是实际计算`d / 2`，因为这避免了浮点值。 
6. 如果机场可达并且其物理距离小于目前看到的最佳距离，则将其基于 1 的索引存储为答案。 目标是接近，因此在所有可行的机场中，最小的物理距离是正确的选择。 
7. 处理完所有机场后，打印存储的索引。 

不变量是在处理完第一个之后`k`机场，存储的候选机场是这些机场中最近的可用机场`k`机场。 每个被拒绝的机场都无法使用，因为它要么没有跑道，要么超出了燃油限制。 每个接受的机场都会与当前最好的机场进行比较，因此在处理下一个机场后，不变式仍然成立。 因此，在最终机场之后，候选机场是所有机场中最近的可用机场。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def opposite(direction):
    return {
        "N": "S",
        "S": "N",
        "E": "W",
        "W": "E",
        "NE": "SW",
        "SW": "NE",
        "NW": "SE",
        "SE": "NW",
    }[direction]

def solve():
    n = int(input())
    fuel = int(input())
    wind = input().strip()

    best_distance = float("inf")
    answer = -1

    for i in range(1, n + 1):
        runway, distance, direction = input().split()
        runway = int(runway)
        distance = int(distance)

        if runway == 0:
            continue

        if direction == wind:
            reachable = distance <= 2 * fuel
        elif direction == opposite(wind):
            reachable = 2 * distance <= fuel
        else:
            reachable = distance <= fuel

        if not reachable:
            continue

        if distance < best_distance:
            best_distance = distance
            answer = i

    print(answer)

if __name__ == "__main__":
    solve()
```使用读取输入`sys.stdin.readline`，这对于线性扫描来说绰绰有余，并且遵循所需的竞争编程 I/O 模式。 

这`opposite`函数将每个罗盘方向转换为其完全相反的方向。 这可以处理基本方向（例如北和南）和对角线方向（例如东北和西南）。 

主循环使用`range(1, n + 1)`这样存储的索引就已经是基于 1 的索引，与输出中预期的机场编号相匹配。 

对于顺风车来说，实际成本是`distance / 2`。 代码不是计算该值，而是检查`distance <= 2 * fuel`。 对于逆风，成本是`2 * distance`，所以测试是`2 * distance <= fuel`。 这些等效的整数比较避免了可能的浮点边界错误。 

该代码在选择最佳机场时会比较物理距离。 风会影响机场是否可达，但声明中的邻近标准是指机场的给定距离。 如果两个可到达的机场具有相同的距离，则保留遇到的第一个机场，因为更新使用`<`而不是`<=`。 

可见声明没有指定如果没有机场可用则应打印什么。 实现使用`-1`对于这种情况。 当隐藏测试需要这种保证时，此类问题的竞赛版本通常会保证有效的机场。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个机场都会读取并处理一次 |
 | 空间| O(1) | O(1) | 仅存储当前机场和最佳候选机场 |

 该解决方案不依赖于可能方向的数量，因为方向计算是常数时间。 即使机场数量非常多，该算法也仅对每个机场执行恒定量的工作，并且不存储机场数组，因此它会随时间线性扩展并使用恒定的辅助内存。 规定的限制为一秒和 256 MB。

 ## 边缘情况

 最重要的边缘情况是物理距离和燃料成本之间的差异。 和```
2
20
S
1 20 S
1 20 N
```机场 1 的距离为 20，但仅需要 10 单位燃料，因为风向和飞行方向一致。 机场 2 具有相同的物理距离，但需要 40 个单位，因为飞机逆风飞行。 扫描接受机场 1 并拒绝机场 2，产生`1`。 这直接锻炼了声明中描述的风调。 

在进行任何距离比较之前，必须拒绝跑道空间为零的机场。 为了```
1
100
N
0 10 N
```飞机有充足的燃料，但跑道数为零。 该算法立即跳过机场并产生`-1`。 这阻止了一个具有吸引力但无法使用的机场成为答案。 

还必须接受确切的燃料边界。 为了```
1
10
N
1 10 N
```有效成本正好是 10，等于可用燃料。 条件使用`<=`，所以机场被接受并且输出是`1`。 替换为`<`会错误地拒绝有效着陆。 

相反方向的计算需要同样的边界处理。 假设飞机有 20 单位燃油，而机场位于相反方向 10 英里之外。 有效成本为`2 * 10 = 20`，所以可以到达机场。 整数测试`2 * distance <= fuel`完全在极限处接受它。 

最后，相等的距离不应导致答案不必要的移动。 如果几个可到达的机场都在 20 英里之外，则扫描会保留第一个机场，因为只有当距离严格较小时，新机场才会取代当前候选机场。 这提供了确定性行为，而无需对机场进行排序或存储它们。
