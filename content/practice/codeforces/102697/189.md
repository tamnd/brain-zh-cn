 ## 解决方案
 ## 问题理解

 我们在三维空间的给定点有一颗恒星。 每个行星也由其三个坐标和一个名称给出。 任务是打印从距离恒星最近的行星到距离恒星最远的行星名称。 

对于一个位于`(x, y, z)`和一颗星`(sx, sy, sz)`，其欧氏距离为`sqrt((x - sx)^2 + (y - sy)^2 + (z - sz)^2)`。 

比较两个距离时不需要平方根。 由于平方根函数对于非负值严格递增，因此比较距离与比较它们的平方距离完全相同。 这让我们可以在整个算法中使用整数运算。 

官方给出了1秒的时间限制和256MB的内存。 它没有发布数字上限`n`在问题页面上，只有`n`是一个正整数。 这使得`O(n log n)`解决自然目标：它对于非常大的输入仍然实用，而`O(n^2)`方法很快就会变得无法使用。 输入本身仅包含每个行星的恒定工作量，因此存储所有行星及其排序键需要线性内存。 

第一个边缘情况是行星的坐标等于恒星的坐标。 例如，```
0 0 0
1
0 0 0 Home
```有输出```
Home
```它的平方距离为零。 一个粗心的实现，初始化到正哨兵的最小距离，但在其他方面正确处理减法，仍然可以工作，而假设每个行星都有严格的正距离的实现可能会错误地处理这种情况。 

第二边缘情况是位于一个或多个轴的负方向上的行星。 例如，```
10 10 10
2
9 10 10 A
8 10 10 B
```有输出```
A
B
```因为距离是`1`和`2`。 必须在平方之前执行减法。 直接比较坐标，或者不小心使用`x - sx`不取平方，就不能代表几何距离。 

第三个常见错误是在排序之前取平方根。 例如，```
0 0 0
2
3 4 0 A
0 0 6 B
```有输出```
A
B
```因为距离的平方是`25`和`36`。 计算实际距离在数学上是可行的，但它引入了浮点运算，但没有提供任何好处。 平方距离给出精确的整数比较。 

输入保证没有两颗行星到恒星的距离相同，因此不需要定义打破平局的规则。 

## 方法

 最直接的蛮力方法就是反复寻找距离最近的尚未打印出来的行星。 在第一次迭代中，我们检查所有`n`行星，在我们检查的第二个`n - 1`， 等等。 距离比较的总数为`n + (n - 1) + ... + 1 = n(n + 1) / 2`。 

因此该方法采用`O(n^2)`时间。 这是正确的，因为每次迭代都会明确选择距离最小的剩余行星，但其二次增长使其不适合以下情况：`n`变大。 为了`n = 100000`，它的性能约为`5 * 10^9`比较，远远超出了1秒的时间限制所能容纳的范围。 

关键的观察结果是，问题只是要求我们通过一个数字键（即行星与恒星的距离）对行星进行排序。 一旦每个行星都附有平方距离，几何部分就完成了。 我们可以把每一对`(squared_distance, name)`放入一个数组并按第一个组件对该数组进行排序。 

蛮力方法之所以有效，是因为它一次发现最少一颗行星，但它会重复扫描相对顺序已确定的行星。 所有行星都可以独立分配距离的观察结果让我们可以计算每个键一次并将排序委托给一个标准`O(n log n)`种类。 

无需计算平方根。 对于两个距离平方的行星`d1²`和`d2²`,`d1 < d2`恰好在什么时候`d1² < d2²`。 Python 整数还可以避免溢出，因此即使是大坐标值也可以安全地求平方。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 对于大 n 来说太慢 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.读取星星的坐标`(sx, sy, sz)`。 每个行星的距离都将相对于同一点进行测量。 
2. 读取行星的数量，并针对每个行星读取`(x, y, z)`和它的名字。 计算`d2 = (x - sx)^2 + (y - sy)^2 + (z - sz)^2`。 

我们使用平方距离是因为它保留了普通距离的顺序，同时避免了平方根和浮点精度。 
3. 商店`(d2, name)`对于数组中的每个行星。 将距离放在第一位，因为这是需要对数组进行排序的值。 
4. 对数组进行排序。 Python 的元组排序主要按第一个组件排序，因此行星会自动按照最小平方距离到最大平方距离的顺序出现。 
5. 按结果顺序打印姓名。 由于输入保证了不同的距离，因此不需要进行平局处理。 

### 为什么它有效

 不变量是每个存储的行星都有一个精确的密钥，等于其距恒星的欧几里德距离的平方。 对于任意两颗行星`A`和`B`，它们的键的顺序与其实际距离的顺序相同，因为平方根在非负数上严格递增。 因此，对这些键进行排序可以准确地产生问题所需的从最近到最远的排序。 任何行星都不会出现在错误的位置，因为排序所做的每一次比较都相当于比较真实的几何距离。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    sx, sy, sz = map(int, input().split())
    n = int(input())

    planets = []

    for _ in range(n):
        x, y, z, name = input().split()
        x = int(x)
        y = int(y)
        z = int(z)

        dx = x - sx
        dy = y - sy
        dz = z - sz

        dist2 = dx * dx + dy * dy + dz * dz
        planets.append((dist2, name))

    planets.sort()

    sys.stdout.write("\n".join(name for _, name in planets))

if __name__ == "__main__":
    solve()
```前两行输入给出了恒星和行星的数量。 然后，循环将三个坐标字段转换为整数，同时将行星名称保留为字符串。 

在平方之前逐个坐标地进行减法。 这是平方 3D 距离公式的直接转换，并且使用三个单独的变量使得更难意外地平方绝对坐标而不是坐标差。 

元组`(dist2, name)`足以进行排序。 Python 按字典顺序比较元组，所以`dist2`决定顺序。 该问题保证了不同的距离，这意味着第二个元组组件永远不会影响答案。 

最终的生成器仅提取名称。`"\n".join(...)`每个输出行只生成一个名称，而不添加不必要的尾随换行符。 Python 中不存在整数溢出问题，因为它的整数具有任意精度。

 ## 边缘情况

 恰好位于恒星坐标处的行星的平方距离为零。 为了```
0 0 0
1
0 0 0 Home
```该算法计算`dx = dy = dz = 0`， 所以`dist2 = 0`。 对单元素数组叶子进行排序`Home`就位，输出是`Home`。 实现中没有特殊情况，因为零自然是最小的可能平方距离。 

负坐标不需要单独处理。 为了```
10 10 10
2
9 10 10 A
8 10 10 B
```该算法计算平方距离`1`和`4`。 分选产品`A`前`B`。 的负值`dx`是无害的，因为它是平方的，这正是欧几里德距离公式所要求的。 

该实现还避免了浮点错误。 为了```
0 0 0
2
3 4 0 A
0 0 6 B
```钥匙是`25`和`36`。 实际距离是`5`和`6`，但计算平方根会增加工作量和浮点值，而不会改变顺序。 整数平方距离给出完全相同的结果。 

最后，行星可能沿着不同的坐标轴有所不同，但具有非常相似的距离。 该实现始终在比较行星之前计算所有三个平方差。 例如，```
0 0 0
2
1 1 1 A
2 0 0 B
```产生平方距离`3`和`4`，所以输出是```
A
B
```仅比较一个坐标的解决方案在这种输入上会失败，而完整的平方距离键正确地包含了所有三个维度。
