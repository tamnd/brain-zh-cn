 ## 解决方案
 ## 问题理解

 我们得到了一组小写单词，并且必须以相反的字母顺序打印相同的单词。 换句话说，按照普通字典顺序最后出现的单词必须首先打印，而首先出现的单词必须最后打印。 

输入包含正整数`n`， 其次是`n`字。 每个单词仅包含小写英文字母。 输出包含完全相同的内容`n`单词，每行一个，但按字典顺序降序排列。 相同的单词可以以任何顺序相邻出现，因为它们是无法区分的。 

发表的声明没有给出明确的上限`n`或字长，但时间限制为 1 秒，内存限制为 256 MB。 这使得显然二次排序过程对于大输入来说是不可取的。 标准比较排序是自然的选择，因为它将单词比较的数量减少到`O(n log n)`。 Python 的内置排序是在优化的本机代码中实现的，因此它也比手动实现排序算法更可取。 

在一些小情况下，实施可能会默默地出错。 例如，用一个词，```
1
apple
```正确的输出是```
apple
```假设必须至少有两个单词的解决方案可能会意外访问不存在的第二个元素。 

重复的单词也必须保留。 为了```
3
cat
cat
apple
```输出是```
cat
cat
apple
```通过将输入转换为集合来删除重复项的解决方案将错误地仅打印两个单词。 

排序的方向是另一个常见的错误。 为了```
3
apple
banana
cat
```正确的输出是```
cat
banana
apple
```使用普通的升序排序而不反转它会产生完全相反的顺序。 

词典比较是对完整的单词进行的，而不是根据长度进行的。 例如，```
3
aa
b
ab
```必须成为```
b
ab
aa
```因为`'b'`大于`'a'`， 尽管`ab`大于`aa`。 按长度排序会产生不同且不正确的结果。 

## 方法

 最直接的暴力方法是反复找到最大的剩余单词，打印它，然后将其从考虑中删除。 在第一次迭代中，我们检查所有`n`话说，我们第二次检查`n - 1`， 等等。 比较次数正好是`n + (n - 1) + ... + 2 + 1 = n(n - 1) / 2`。 

该过程是正确的，因为每次迭代都明确选择尚未打印的最大单词。 然而，当它的二次比较次数变得昂贵时`n`很大。 为了`n = 100000`，确切的比较计数是`4,999,950,000`，这远远超出了 1 秒解决方案应尝试的范围。 反复从 Python 列表中间删除元素可能会使情况变得更糟，因为删除本身可能需要线性时间。 

关键的观察结果是，该问题没有超出普通词典顺序的特殊结构。 我们不需要发明自定义的贪婪规则或单独利用这些字母。 期望的结果只是与正常排序顺序相反。 比较排序可以排列所有单词`O(n log n)`比较，然后请求降序排列即可准确给出所需的序列。 

暴力方法之所以有效，是因为它直接发现下一个最大值，但它重新发现排序算法可以更有效地组织的信息。 整个任务只是降序字典顺序的观察让我们可以用一种标准排序代替重复的最大搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) 单词比较 | O(n) | 对于大 n 来说太慢 |
 | 最佳 | O(n log n) 比较 | O(n) 辅助/参考空间 | 已接受 |

 如果考虑单词比较本身，它们的成本取决于公共前缀的长度。 具有最大字长`L`，比较排序的实际上限是`O(n log n * L)`。 Python 本身存储输入单词，因此字符串所需的内存与其总输入大小成正比。 

## 算法演练

 1. 阅读`n`然后阅读`n`单词放入列表中。 我们保留每个出现的单词，因为输出必须完全包含输入单词，包括重复项。 
2. 按字典顺序降序对列表进行排序。 蟒蛇的`sorted(..., reverse=True)`执行普通的字典排序并反转所请求的顺序，这正是所需的从最大到最小的字典顺序。 
3. 打印排序后的单词，每行一个。 用换行符连接它们可以避免重复的输出调用并直接生成所需的格式。 

### 为什么它有效

 在排序步骤之后，列表被排序，以便对于每个相邻的对`a[i]`和`a[i + 1]`,`a[i]`按字典顺序大于或等于`a[i + 1]`。 因此，第一个元素是最大的单词，第二个元素是剩余单词中最大的单词，依此类推。 由于排序不会删除或重复元素，因此最终列表完全包含按所需的相反字母顺序排列的原始单词。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    words = [input().strip() for _ in range(n)]

    words.sort(reverse=True)

    sys.stdout.write("\n".join(words))

if __name__ == "__main__":
    solve()
```第一行读取单词数。 的价值`n`只需要知道有多少后续行属于输入。 

列表理解准确地读取了那些`n`字。 呼唤`strip()`删除插入的换行符`readline()`而不改变构成单词的小写字母。`words.sort(reverse=True)`是中心操作。 Python 按字典顺序逐个字符地比较字符串，这与小写英文单词的字母顺序相匹配。`reverse=True`将方向从上升更改为下降。 

决赛`join`生成一个以换行符分隔的字符串。 不需要在最后一个单词后添加特殊的换行符，因为输出格式接受没有换行符的最后一行。 

不执行涉及输入大小的整数算术，因此整数溢出在 Python 中是无关紧要的。 要避免的主要实现细节是意外使用`sorted(words)`没有`reverse=True`，这将产生升序而不是降序。 

## 工作示例

 对于第一个示例，输入包含两个单词。 

| 步骤| 排序前的单词 | 行动| 结果 |
 | ---| ---| ---| ---|
 | 1 |`["coderams", "club"]`| 阅读这两个词 |`["coderams", "club"]`|
 | 2 |`["coderams", "club"]`| 字典顺序降序 |`["coderams", "club"]`|
 | 3 |`["coderams", "club"]`| 按顺序打印 |`coderams`,`club`|`coderams`之后`club`按字典顺序升序，因为两者都以`c`，但第二个字符是`o`和`l`， 和`o > l`。 因此颠倒正常顺序`coderams`第一的。 

对于第二个示例，单词排列如下。 

| 步骤| 当前状态 | 行动|
 | ---| ---| ---|
 | 1 |`hello, world, we, hope, you, enjoy, the, contest, today, good, luck`| 阅读所有单词 |

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log n·L) | O(n log n · L) | 排序执行 O(n log n) 次比较，对于最大长度 L | 的单词，每次比较最多占用 O(L) 时间。 
| 空间| O(n·L) | O(n·L) | 输入列表存储了所有单词，而Python的排序也使用了辅助内存 |

 预期的算法用标准的二次重复最大搜索代替`O(n log n)`比较排序。 对于大量单词，这种差异是巨大的，并且实现使用 Python 的优化内置排序例程来轻松地将预期输入大小保持在规定的 1 秒时间限制内。 内存使用量主要由存储输入单词决定，并且与输入大小呈线性关系。

 ## 边缘情况

 单字情况的处理无需任何特殊分支。 对于输入```
1
apple
```该列表最初仅包含`apple`。 对单元素列表进行排序使其保持不变，因此算法会打印`apple`。 假设两个或多个元素的粗心实现可能会在这里失败，但内置排序自然会处理边界。 

重复值仍然存在，因为算法对原始列表进行排序而不是构建集合。 为了```
3
cat
cat
apple
```排序后的列表是`cat, cat, apple`。 两次出现`cat`参与排序并打印。 输出完全包含原始元素的不变量被保留。 

排序方向由`reverse=True`。 为了```
3
apple
banana
cat
```升序排序会产生`apple, banana, cat`，但降序排序会产生`cat, banana, apple`，这是所需的输出。 该实现直接指定方向，而不是排序和手动反转索引范围，从而避免了不必要的差一错误。 

不同长度的单词按字典顺序进行比较，而不是按长度进行比较。 为了```
3
aa
a
ab
```该算法首先比较公共前缀`a`。 自从`a`在该前缀之后结束，它比两者都小`aa`和`ab`。 之间`aa`和`ab`，第二个字符决定顺序，所以最终的结果是```
ab
aa
a
```这遵循 Python 字符串使用的相同比较规则并匹配字母顺序。 

大输入情况不需要不同的算法。 对于 100000 个单词，反复查找最大值需要`100000 * 99999 / 2 = 4,999,950,000`最坏情况下的两两比较。 排序解决方案按照以下顺序执行`100000 log₂(100000)`，在考虑比较每个单词内的字符的成本之前，大约有 170 万个比较位置。 这种差异就是为什么使用标准`O(n log n)`排序是解决方案的重要部分。
