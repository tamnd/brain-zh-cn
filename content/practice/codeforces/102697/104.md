 ## 解决方案
 ## 问题理解

 列车网络可以建模为无向图。 每个城市都是一个顶点，每条火车线路都是无向边，因为线路可以沿任一方向行驶。 给定一个特定的城市作为起点，我们需要计算使用任意数量的火车线路可以从该城市到达多少个不同的城市。 官方问题明确建议使用 BFS，并要求在运行图遍历之前将城市名称映射到数字标识符。 

第一输入行给出城市的数量`n`和火车线路`m`。 下一行给出起始城市名称。 以下每一项`m`lines 包含由火车线路连接的两个城市名称。 输出是包含起始城市的连接组件的大小。 

该声明没有公布明确的上限`n`和`m`，所以我们不应该假设一个小图。 时间限制仅为 1 秒，内存限制为 256 MB。 这强烈支持线性图遍历，`O(n + m)`，而不是在探索城市时重复扫描所有火车线路。 邻接表准确地存储了 BFS 所需的关系，因此构建和遍历都与输入图的大小保持线性关系。 

城市名称是字符串而不是整数 ID。 尝试使用城市名称作为数组索引的直接实现是不可能的，因此需要一个字典将每个遇到的名称映射到整数。 另一个微妙的问题是一个城市可能出现多条火车线路。 我们必须计算一次，而不是每个事件边计算一次。 

考虑以下断开的网络。```
4 2
A
A B
C D
```正确的输出是`2`。 开始于`A`，我们可以达到`B`，但是没有从它们中的任何一个到`C`或者`D`。 计算输入中出现的每个城市的实现将错误地返回`4`。 

第二个边缘情况是循环。```
3 3
A
A B
B C
C A
```正确的输出是`3`。 BFS可能会遇到`A`处理时再次`C`，但它不能入队或计数`A`第二次。 如果没有访问过的结构，则遍历可以围绕循环反复行走。 

起始城市也可以根本没有火车线路。```
1 0
A
```正确的输出是`1`。 从自身可达需要零火车乘坐，因此起始城市属于可达集，即使它没有边缘。 

## 方法

 一个简单但低效的实现可以将火车线路表示为一对列表。 每当 BFS 处理一个城市时，它都会扫描整个城市列表`m`火车线路来查找哪些线路触及该城市。 这是正确的，因为每个可能的连接都会被检查，但是处理`v`可到达的城市可能需要扫描所有`m`每次都有边缘。 在最坏的情况下，当所有`n`城市可达，这意味着`n * m`边缘检查。 对于稠密图`m`按顺序`n²`，这就变成了`O(n³)`，即使对于稀疏图，重复检查不相关的火车线路也会浪费工作。 

关键的观察结果是该图是静态的。 在BFS开始之前，我们可以按城市对火车线路进行分组。 对于每个城市`u`，存储一个列表，其中包含直接连接的城市`u`。 那么当BFS达到`u`，没有理由检查任何不相关的边。 我们简单地迭代一下`u`的邻接表。 

因为每条无向列车线路都存储两次，一次在每个端点的邻接列表中，所以存储的邻接条目总数为`2m`。 BFS 最多访问每个城市一次，并且最多处理每个存储的邻接条目一次。 因此完整的遍历是`O(n + m)`。 

用于城市名称压缩的字典使其变得实用。 当第一次遇到城市名称时，为其分配下一个可用整数。 该名称的所有后续出现均指同一个顶点。 然后，图算法可以对整数数组和列表进行操作，而不是重复比较字符串。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(纳米) | O(n + m) | 太慢了 |
 | 最佳 | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 阅读`n`,`m`，以及起始城市名称。 创建一个将城市名称映射到整数 ID 的字典，并为该图创建一个邻接表。 由于该语句直接给出城市名称而不是数字顶点标签，因此字典提供了缺失的数字表示。 
2. 阅读每条列车线路。 将两个端点名称转换为整数 ID，在第一次看到名称时创建新 ID。 将每个端点添加到另一个端点的邻接列表中，因为火车线路在两个方向上都可用。 
3. 将起始城市名称转换为其整数 ID。 将其标记为已访问并将其放入队列中。 立即标记它，而不是等到它从队​​列中删除，可以防止当多个已发现的城市指向同一城市时多次插入该城市。 
4. 反复从队列前面删除一个城市。 检查邻接列表中的每个邻居。 对于每个尚未访问过的邻居，将其标记为已访问，增加可达城市计数，并将其附加到队列中。 
5. 当队列变空时停止。 此时，没有已发现的城市具有未探索的传出连接，因此已找到从起始城市可到达的每个城市。 输出访问过的城市数量。 

它的工作原理可以用一个简单的不变量来表达：在每次 BFS 操作之后，每个访问的城市从一开始都是可达的，并且每个可达城市的距离最多为已探索的图的部分已经被发现。 处理访问的城市时，会考虑每个直接邻居。 因此，任何可到达的城市最终都会进入队列。 由于城市在入队之前就被标记为已访问过，因此每个城市都会被精确计数一次。 当队列变空时，不再有可到达的未发现的邻居，因此计数恰好是起始城市的连接组件的大小。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    start = input().strip()

    city_id = {}
    graph = [[] for _ in range(n)]

    def get_id(name):
        if name not in city_id:
            city_id[name] = len(city_id)
        return city_id[name]

    start_id = get_id(start)

    for _ in range(m):
        a, b = input().split()

        u = get_id(a)
        v = get_id(b)

        graph[u].append(v)
        graph[v].append(u)

    visited = [False] * len(city_id)
    visited[start_id] = True

    queue = deque([start_id])
    answer = 1

    while queue:
        u = queue.popleft()

        for v in graph[u]:
            if not visited[v]:
                visited[v] = True
                answer += 1
                queue.append(v)

    print(answer)

if __name__ == "__main__":
    solve()
```字典`city_id`执行从任意城市名称到连续整数的坐标压缩。`get_id`有意用于每条列车线路的两个端点，因此相同的名称始终接收相同的顶点 ID。 

该图被构造为无向邻接表。 两人`append`操作都是必要的。 省略反向边会意外地将火车网络变成有向图。 

该队列包含仍需要处理邻接列表的城市。`visited[start_id]`在第一次入队之前设置，每个新发现的城市在入队之前都会被标记。 这种排序可以防止图表中出现重复，其中包含同一城市之间的循环或多条路径。 

答案开始于`1`因为起始城市本身是可以到达的。 随后的每一个增量都对应一个之前未见过的城市，因此最终值正是可到达城市的数量。 

Python 整数不会溢出，最大的数据结构与城市名称和火车线路端点的数量成正比。 该实现还避免了`list.pop(0)`，这将使队列操作`O(n)`。`collections.deque.popleft()`提供恒定时间队列删除。 

有一个实现细节值得仔细处理：该语句给出了`n`，但它没有提供包含所有内容的单独列表`n`城市名称。 这些名称是从出发城市和火车线路的终点发现的。 邻接表最初分配为`n`插槽，同时`visited`在遇到所有名称后确定大小。 这是安全的，因为输入通过这些名称描述图形。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + m) | 每个城市都会被访问一次，每条无向列车线路都会贡献两个邻接条目，并检查一次。 |
 | 空间| O(n + m) | 字典、访问数组、队列和邻接表一起使用线性空间。 |

 官方给出的限制是 1 秒和 256 MB，但声明中没有公布数字上限`n`和`m`。 线性解是合适的目标，因为它直接随输入大小缩放。 邻接表示还避免了分配与产品成比例的工作`n * m`，这是暴力方法的主要弱点。

 ## 边缘情况

 孤立的起始城市是最小的有意义的图。 为了```
1 0
A
```字典指定`A`一个 ID，BFS 开头`A`，处理完后队列立即变空。 答案依然存在`1`。 仅当发现邻居时才增加答案的实现会错误地打印`0`。 

断开连接的图测试遍历是否遵循可达性，而不是简单地计算输入名称。 为了```
6 4
A
A B
B C
D E
E F
```BFS 开始于`A`，发现`B`，然后发现`C`。 从该组件到`D`， 所以`D`,`E`， 和`F`永远不会插入队列中。 输出是`3`。 

循环会暴露重复排队错误。 和```
4 4
A
A B
B C
C D
D A
```BFS首先发现`B`从`A`。 然后它发现`C`从`B`， 和`D`从`C`。 什么时候`D`被处理，它看到`A`， 但`A`已被标记为已访问，因此被忽略。 输出是`4`，并且遍历终止而不是围绕循环循环。 

前往同一城市的多条路线的行为类似。 在```
4 4
A
A B
A C
B D
C D
```两个都`B`和`C`最终检查`D`。 无论哪一个处理`D`首先标记它已访问并将其排入队列。 第二次遇到看到访问的标志但不执行任何操作。 最终的答案是`4`，展示了为什么城市必须在发现时进行标记，而不是在边缘到达时进行计数。 

最后，一条链，例如```
5 4
A
A B
B C
C D
D E
```检查遍历边界。 BFS 访问`A`， 然后`B`,`C`,`D`，最后`E`。 什么时候`E`处理完毕后，其邻接列表仅包含已访问过的城市，因此队列变空，答案为`5`。 仅计算新发现的邻居的逐一实现将错过起始城市，而在处理最终排队顶点之前停止的实现可能会错过`E`。
