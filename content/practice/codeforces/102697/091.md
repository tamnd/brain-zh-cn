 ## 解决方案
 ## 问题理解

 这两个太空实验室位于太阳系的行星上。 行星按照距太阳的距离有固定的顺序：`Mercury, Venus, Earth, Mars, Jupiter, Saturn, Uranus, Neptune`。 

输入在第一行给出包含您的太空实验室的行星，在第二行给出包含竞争对手太空实验室的行星。 任务只是比较它们在这个有序序列中的位置。 如果你的行星出现较早，请打印`CLOSER`。 如果稍后出现，则打印`FARTHER AWAY`。 如果两个名字相等，则打印`THE SAME`。 

只有八个可能的行星名称，并且输入始终包含有效的太阳系行星。 运行时间限制为一秒，内存限制为256 MB。 由于输入本身仅包含来自一组固定的八个值的两个短字符串，因此即使对所有行星进行线性扫描也最多执行少量比较。 这里不存在时间限制问题的重大风险。 主要目标是将行星的口头顺序转变为程序可以直接比较的东西。 

第一个边缘情况是两个太空实验室位于同一个星球上。 例如：```
Neptune
Neptune
```正确的输出是：```
THE SAME
```一个粗心的实现，只检查第一个行星是在第二个行星之前还是之后，可能会失败，而不会产生所需的相等结果。 

第二种边缘情况是第一个行星是最远的行星，而第二个行星是最近的：```
Neptune
Mercury
```正确的输出是：```
FARTHER AWAY
```意外地向后解释行星顺序的实现将产生相反的答案。 

第三个有用的边界情况是两个相邻的行星：```
Earth
Mars
```正确的输出是：```
CLOSER
```这可以捕获基于索引的表示中的微小错误。 从零开始计算时，地球的索引为 2，火星的索引为 3，因此地球必须被归类为更接近的。 

## 方法

 最直接的方法是按照距太阳的顺序存储八颗行星，并搜索该数组以找到每个输入行星的位置。 如果第一颗行星被发现在位置`a`第二个位置`b`, 比较`a`和`b`立即给出答案。 对于大小恒定的集合来说，这实际上是蛮力。 在最坏的情况下，找到每个行星需要检查所有八个条目，因此最多有 16 个行星名称比较。 

由于列表的大小固定为 8，因此这种方法已经足够快了。 对于这个特定问题，不存在扫描变得有问题的输入大小。 尽管如此，通过观察我们需要从行星名称中获得的唯一信息是它在排序中的位置，可以使基本思想变得更清晰。 字典将每个名称直接映射到其位置，因此每次查找都需要预期的结果`O(1)`时间。 

蛮力扫描之所以有效，是因为搜索空间仅包含八颗行星，但通过观察行星顺序是固定的，我们可以用数字排名来表示每个行星。 一旦两个名字都被转换为排名，剩下的问题就是一个普通的整数比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(8)，实际上是 O(1) | O(8)，实际上是 O(1) | 已接受 |
 | 最佳 | 预期 O(1) | O(8)，实际上是 O(1) | 已接受 |

 在编辑解决方案中，字典版本更可取，因为它直接表达了中心思想：每个行星都有固定的排名，答案仅取决于比较这些排名。 

## 算法演练

 1. 按照从太阳开始的顺序，创建从每个行星名称到其位置的映射。 水星排名 0，金星排名 1，海王星排名 7。确切的数值并不重要，重要的是它们的相对顺序。 
2. 从输入中读取两个行星名称。 第一个名称属于我们的太空实验室，第二个名称属于竞争对手的太空实验室。 
3. 在映射中查找两个名称。 这将有关行星名称的原始问题转换为两个整数之间的比较。 
4. 比较两个等级。 如果我们的排名更小，我们的星球离太阳更近，所以打印`CLOSER`。 如果我们的排名更大，则打印`FARTHER AWAY`。 如果排名相等，则两个太空实验室位于同一个星球上，因此打印`THE SAME`。 

### 为什么它有效

 该映射准确地保留了问题指定的顺序：较小的等级意味着行星离太阳更近。 因此，将两个行星名称转换为等级后，每个可能的行星对都恰好属于三种情况之一。 我们的排名可以小于、大于或等于竞争对手的排名，这三种情况恰好对应于三个所需的输出字符串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    order = {
        "Mercury": 0,
        "Venus": 1,
        "Earth": 2,
        "Mars": 3,
        "Jupiter": 4,
        "Saturn": 5,
        "Uranus": 6,
        "Neptune": 7,
    }

    mine = input().strip()
    rival = input().strip()

    a = order[mine]
    b = order[rival]

    if a < b:
        print("CLOSER")
    elif a > b:
        print("FARTHER AWAY")
    else:
        print("THE SAME")

if __name__ == "__main__":
    solve()
```这`order`字典是算法演练步骤 1 中的核心数据结构。随着行星离太阳越来越远，这些值会增加，因此比较它们与比较问题中的物理位置具有相同的含义。 

这两个电话`input()`准确地读出两个行星的名称。 使用`.strip()`删除换行符而不更改行星名称本身。 

这三个分支直接对应了两个等级之间的三种可能的关系。 平等分支是必要的，因为两个空间实验室的行星可以是相同的。 

不存在整数溢出问题，因为排名范围仅从 0 到 7。字典查找也不需要边界检查，因为该语句保证两个名称都是有效的行星。

 ## 边缘情况

 对于相等的行星，请考虑：```
Neptune
Neptune
```两次字典查找都产生排名 7。`a < b`和`a > b`都是假的，算法到达相等分支并打印`THE SAME`。 这可以防止将平等视为更近或更远的常见错误。 

对于极端排序，请考虑：```
Neptune
Mercury
```排名是 7 和 0。第一个排名较大，因此算法打印`FARTHER AWAY`。 不需要对第一个或最后一个行星进行特殊处理，因为等级表示自然会处理两个边界。 

对于相邻行星，请考虑：```
Earth
Mars
```地球映射到 2，火星映射到 3。由于 2 小于 3，所以结果是`CLOSER`。 将输入反转为`Mars`和`Earth`产生排名 3 和 2，因此`FARTHER AWAY`。 这证实了该实现比较了实际的排序，而不是依赖于字母顺序或名称的文本外观。
