 ## 解决方案
 ## 问题理解

 该任务比标题所暗示的要简单得多。 我们在这一年中进行了 (n) 笔付款，每笔付款均以正整数形式给出，以美分表示其金额。 所需的答案是花费的总金额，也以美分为单位。 输入包含 (n) 后跟 (n) 个付款金额，每行一个金额，输出是它们的总和。 

官方限制为 1 秒和 256 MB。 该声明没有公布 (n) 或单独付款的明确上限，因此没有可以从声明本身得出的精确的最坏情况操作计数。 因此，正确的算法应该随着支付数量线性扩展，并且不应该执行任何随着支付价值而增长的工作。 读取每笔付款并添加一次就给出了这种行为。 Python 整数还避免了普通整数输入的固定宽度溢出问题。 

在一些小情况下，实施可能会出错。 一次性付款，例如```
1
42
```答案是`42`。 从不存在的第一个元素而不是从零初始化总计的代码在这里可能会失败。 

重复值必须独立计数。 为了```
3
5
5
5
```答案是`15`， 不是`5`。 意外地将付款视为一组的实现会默默地丢弃重复项。 

总额可能大于任何个人付款。 为了```
4
100
200
300
400
```答案是`1000`。 仅跟踪最大付款或将任务与查找最大值混淆的实现会产生错误的结果。 

最后，付款以美分为单位，因此不需要小数转换。 例如，```
2
99
1
```产生`100`。 将这些值视为浮点美元金额会增加不必要的复杂性，并可能引入舍入问题。 

## 方法

 一种直接的方法是将每笔付款读入一个数组，然后迭代该数组来计算总数。 这是正确的，因为每笔付款都只为最终金额贡献一次。 如果有 (n) 次支付，则除了 (n) 次输入操作之外，第二遍还执行 (n) 次加法。 它的时间复杂度为 (O(n))，这已经是可能的最小渐近时间，因为每次付款都必须从输入中读取。 

这个问题中没有隐藏有意义的子集搜索或组合强力。 例如，尝试每个子集将执行 (2^n) 工作，即使问题从未要求我们选择付款。 这种方法将解决比给定问题困难得多的问题。 

有用的观察是最终答案是关联和。 在将付款添加到运行总额后，我们不需要记住付款。 当下一笔付款到达时，所有先前付款的唯一重要信息是它们的总金额。 

这将两遍数组方法转变为单遍流解决方案。 开始于`total = 0`，读取每笔付款，并立即将其添加到`total`。 最后付款后，`total`正是所需的答案。 时间仍然是 (O(n))，但额外的空间从 (O(n)) 下降到 (O(1))。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 存储所有付款，然后求和 | (O(n)) | (O(n)) | (O(n)) | (O(n)) | 已接受，但不必要的存储 |
 | 运行总和 | (O(n)) | (O(n)) | (O(1)) | (O(1)) | 已被接受且最佳 |

 ## 算法演练

 1. 读取付款次数 (n)。 这准确地告诉我们必须从输入中消耗多少支付金额。 
2. 初始化`total`为零。 零是加法的恒等值，因此添加第一笔付款会产生正确的贡献，而不需要特殊的第一元素情况。 
3. 重复 (n) 次。 读取一笔付款并将其立即添加到`total`。 付款不需要存储，因为以后的计算不需要其单独的值。 
4. 打印`total`处理完所有付款后。 那时，每笔输入付款都只贡献了一次。 

为什么有效：在处理任何付款前缀后，`total`等于该前缀的总和。 最初前缀为空且总和为零。 当读取下一次付款（m）时，新值变为前一个前缀和加上（m），因此不变式保持为真。 处理完所有 (n) 笔付款后，前缀是整个输入序列，使得`total`等于所需的总支出。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    total = 0

    for _ in range(n):
        total += int(input())

    print(total)

if __name__ == "__main__":
    solve()
```第一行读取 (n)，它控制循环而不是依赖于文件结尾检测。 这与输入格式完全匹配，并保证精确消耗指定数量的付款。`total`从零开始，因为加法的恒等式为零。 这也可以处理没有单独分支的单次支付情况。 

每笔付款都会转换为整数并立即相加。 订单的重要性仅在于每笔付款必须处理一次。 美分和美元之间没有排序、比较或换算。 

Python 的整数类型可以根据需要增长，因此该实现不存在使用小整数类型的语言中可能出现的固定宽度溢出问题。 除了运行时处理的输入缓冲之外，内存使用量保持不变。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | (O(n)) | (O(n)) | 每笔付款都会被读取并添加一次 |
 | 空间| (O(1)) | (O(1)) | 仅有的`n`并存储运行总计 |

 线性运行时间是合适的，因为输入本身包含 (n) 个支付值，因此任何正确的解决方案都必须检查这些值。 该算法不会执行与付款金额成比例的任何额外工作，并且它不存储付款数组。

import io

def solve():
    input = sys.stdin.readline

## 边缘情况

 对于单次付款，```
1
42
```算法初始化`total`为零，读取`42`，并将总计更改为`42`。 然后它立即打印该值。 不会尝试访问第一个输入值之前的元素，因此自然会处理最小的有效输入。 

对于重复付款，```
3
5
5
5
```运行总计是`5`,`10`， 和`15`。 该算法从不删除重复的值，这是正确的，因为三笔单独的 5 美分支付代表了 15 美分的支出。 

对于大于每笔单独付款的总额，```
4
100
200
300
400
```运行总计是`100`,`300`,`600`， 和`1000`。 最终的结果来自于积累，而不是选择任何单一的支付。 

对于跨越圆形边界的总和，```
2
99
1
```第一次付款产生`99`，第二个将其更改为`100`。 由于这些值被视为整数分，因此不存在可以改变答案的浮点算术或舍入步骤。
