 ## 解决方案
 ## 问题理解

 任务是仅使用十进制数字 4 和 7，其中 4 和 7 的数量完全相同，找到至少为给定数字 (n) 的最小整数。 这样的数字被称为超级幸运。 输入包含一个正整数，但其值最多可以有 100,000 位十进制数字，因此必须将其视为字符串而不是转换为机器整数。 输出是满足下界的最小超级幸运数。 

超级幸运数字的长度必须是偶数，因为它的数字必须在 4 和 7 之间平均分配。如果输入长度是奇数，则不存在该长度的超级幸运数字，因此答案必须立即使用下一个偶数长度。 对于 100,000 位数字，枚举候选人是完全不可能的。 有 (2^{100000}) 个字符串仅由 4 和 7 组成，甚至将我们限制为平衡字符串留下 (\binom{100000}{50000}) 个候选。 预期的解决方案必须在线性时间内处理十进制表示。 原问题的时间限制为 2 秒，并且允许 (n) 有 100,000 个数字。 

在某些情况下，粗心的实施可能会悄无声息地出错。 用于输入`47`，这个数字本身就已经超级幸运了，所以正确的输出是`47`。 总是搜索严格更大的数字的实现会错误地产生`74`。 

用于输入`1`，长度为奇数。 不可能存在一位数平衡的幸运数，所以答案是两位数最小的平衡幸运数，`47`。 仅在具有相同长度的数字之间进行搜索的实现在这里将失败。 

用于输入`4500`，正确的输出是`4747`。 第一个数字可以保持等于4，但第二个数字5不能用作幸运数字。 我们必须将该位置增加到 7，然后用 1 个 4 和 1 个 7 填充剩余位置。仅考虑将现有 4 更改为 7 的解决方案将错过用 7 替换无效数字（例如 5）的可能性。 

用于输入`7777`，至少不能输入四位超级幸运数字。 开头的每一个可能的改变都会在前缀中留下太多的 7，所以答案移动到下一个偶数长度并变成`444777`。 假设始终存在相同长度答案的实现将构造无效数字或超出字符串的开头。 

## 方法

 直接的暴力解决方案将生成相关长度的每个幸运数字，保留包含相同数量的 4 和 7 的数字，并选择第一个至少为 (n) 的数字。 对于长度 (L)，恰好有 (2^L) 个字符串仅包含 4 和 7。在最坏的情况下 (L=100000)，这意味着恰好 (2^{100000}) 个候选者，甚至在检查它们的数字计数是否平衡之前。 如果我们只生成平衡的候选者，它们的数量仍然是（\binom{100000}{50000}），这是一个天文数字。 根据 (n) 检查每个候选者本身可能需要 (O(L)) 字符比较。 蛮力方法是正确的，因为它明确地检查整个候选集，但其指数增长使其无法使用。 

有用的观察是我们不需要独立构建候选者。 所有相同长度的超级幸运数字恰好有一半的位置被 4 占据，一半被 7 占据。当比较两个相同长度的数字时，它们不同的第一个位置决定哪个较小。 这意味着我们应该尽可能长时间地保持前缀等于 (n)。 在第一个不再相等的位置，我们希望将该数字增加尽可能小的数量，然后使后缀尽可能小。 

幸运数字只有两位，因此任何位置最多只有一位有用的较大数字。 如果输入的数字是4，我们可以将其替换为7。如果输入的数字是0到3，我们可以将其替换为4。如果输入的数字是5或6，我们可以将其替换为7。如果是7、8或9，则没有比它更大的幸运数字。 一旦位置增加，后缀应包含所有剩余的 4，然后再包含所有剩余的 7，因为 4 是较小的数字。 

微妙的部分是选择增加的位置。 后面的位置总是比前面的位置更可取，因为它保留了等于 (n) 的较长前缀。 从左到右扫描时，我们可以记住可以增加当前数字的最新位置，同时将数字计数保持在所需的限制内。 如果原来的号码已经超级幸运，我们会立即将其退回。 如果不存在可行的增加，则没有相同长度的答案，因此我们使用下一个偶数长度的最小超级幸运数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(L·2^L) | O(L·2^L) | O(L) | 太慢了 |
 | 最佳| O(L) | O(L) | 已接受 |

 ## 算法演练

1. 将(n)读取为字符串，并设其长度为(L)。 我们从不将其转换为整数，因为 (L) 可以是 100,000，远远超出正常机器整数范围。 
2. 如果(L)是奇数，则将其加一并构造该长度的最小超级幸运数。 由于 4 小于 7，因此该数字是由 (L/2) 个 4 和后跟 (L/2) 个 7 组成的块。 奇数长度的数字永远不可能包含相等数量的两个数字。 
3. 如果 (L) 是偶数，首先检查 (n) 本身是否仅包含 4 和 7 个且恰好包含每个副本的 (L/2) 个副本。 如果是，则它已经是最小的可能答案，因为所需的值至少为 (n)。 
4. 从左到右扫描数字，同时保留前缀中 4 和 7 的数量。 在位置(i)处，(i)之前的前缀必须完全由幸运数字组成。 如果已经出现无效数字，则后面的位置不能用作第一个更改的位置，因为未更改的前缀将包含该无效数字。 
5、在当前位置，确定严格大于(n[i])的最小幸运数字。 对于低于 4 的数字，这是 4，对于 5 或​​ 6，它是 7，对于 4，它是 7。数字 7、8 和 9 没有更大的幸运数字。 
6. 检查放置较大的数字是否会使任一数字计数超过 (L/2)。 如果可行的话，记住这个位置和替换的数字。 我们故意继续扫描，因为稍后的可行位置通过保留更多的原始前缀来产生更小的最终数字。 
7. 扫描后，如果找到可行的位置，则复制该位置之前的前缀，将记住的较大数字放在那里，并在剩余位置中填充所需数量的 4，然后填充所需数量的 7。 该后缀按字典顺序最小，因为每 4 都小于每 7。 
8、如果不存在可行位置，构造长度为(L+2)的最小超级幸运数。 每个具有更多位数的数字都大于每个（L）位数的数字，因此这是正确的后备。 

不变量是每个记住的候选者都有一个与 (n) 相同的前缀，后跟候选者变大的第一个位置。 它的数字计数仍然可以精确到每个数字的 (L/2) 个副本。 在所有此类候选者中，最新更改的位置与 (n) 的公共前缀最长，因此它是最小的。 一旦确定了该位置，将所有剩余的 4 放在所有剩余的 7 之前即可给出尽可能小的后缀。 如果不存在这样的位置，则相同长度的超级幸运数不能至少为(n)，因此增加长度是不可避免的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve(n: str) -> str:
    length = len(n)

    # An odd length cannot contain equal numbers of 4 and 7.
    if length % 2 == 1:
        half = (length + 1) // 2
        return '4' * half + '7' * half

    half = length // 2

    # If n is already super lucky, it is the answer.
    if n.count('4') == half and n.count('7') == half:
        return n

    count4 = 0
    count7 = 0

    best_pos = -1
    best_digit = ''

    for i, ch in enumerate(n):
        if ch not in '47':
            # Find the smallest lucky digit strictly greater than ch.
            if ch < '4':
                digit = '4'
            elif ch < '7':
                digit = '7'
            else:
                digit = ''

            if digit:
                new4 = count4 + (digit == '4')
                new7 = count7 + (digit == '7')

                if new4 <= half and new7 <= half:
                    best_pos = i
                    best_digit = digit

            # The unchanged prefix would contain an invalid digit,
            # so no later position can be the first changed position.
            break

        # ch is lucky. It can only be increased if it is 4.
        if ch == '4':
            if count4 <= half and count7 + 1 <= half:
                best_pos = i
                best_digit = '7'
            count4 += 1
        else:
            count7 += 1

    if best_pos == -1:
        # No valid answer with the same length.
        new_length = length + 2
        half = new_length // 2
        return '4' * half + '7' * half

    # Use the longest possible unchanged prefix.
    prefix = n[:best_pos]
    new4 = count4
    new7 = count7

    # The counts above correspond to the prefix when best_pos is after
    # the scan, so recompute them directly for the chosen prefix.
    new4 = prefix.count('4')
    new7 = prefix.count('7')

    if best_digit == '4':
        new4 += 1
    else:
        new7 += 1

    remaining4 = half - new4
    remaining7 = half - new7

    return prefix + best_digit + '4' * remaining4 + '7' * remaining7

def main():
    n = input().strip()
    print(solve(n))

if __name__ == "__main__":
    main()
```在进行任何详细比较之前，第一个分支处理奇数长度。 新的长度是大于输入长度的最小偶数长度，并且按字典顺序排列的最小计数相等的字符串是全 4 后面全是 7。 

精确匹配检查使用这样的事实：偶数长度的超级幸运数必须完全包含`half`两个数字的副本。 立即返回可以防止贪婪搜索不必要地产生严格更大的数字。 

在主扫描期间，`count4`和`count7`描述当前位置之前未更改的前缀。 当当前数字为4时，将其更改为7是唯一可能的方法，使数字更大，同时保持幸运。 当当前数字不幸运时，代码会尝试超过它的最小幸运数字。 扫描在第一个无效数字后停止，因为任何后来的候选者都必须保留该无效数字不变。 

这`best_pos`变量存储最新的可行增量。 存储最新的而不是第一个是关键的贪婪选择。 后来的更改保留了原始数字的更多数字，从而使结果数字更小。 

扫描后，代码使用剩余数量的 4 和剩余数量的 7 重建后缀。 该实现始终使用字符串运算，因此它从不对 100,000 位整数执行算术运算。 因此，Python 的整数转换限制是无关紧要的。 

这`prefix.count`在选择候选位置后，调用仅发生一次，因此它们最多添加另一个线性传递。 总运行时间保持线性。 在表达式中使用 Python 布尔值，例如`digit == '4'`是故意的，因为`True`和`False`添加到计数中时表现为 1 和 0。

 ## 工作示例

 对于第一个样本，`n = 4500`，长度为 4，一半为 2。这个数字本身并不是超级幸运，因为它的数字并不全是 4 和 7。扫描过程如下。 

| 职位| 数字| 4 秒前 | 7 秒前 | 可能更大的幸运数字| 可行的候选人 |
 | ---| ---| ---| ---| ---| ---|
 | 0 | 4 | 0 | 0 | 7 | 7 |
 | 1 | 5 | 1 | 0 | 7 | 7 |

 在位置 0，将 4 更改为 7 给出了有效的候选者，但我们继续，因为稍后的更改更可取。 在位置1处，数字5也可以变成7，前缀`4`为剩余的数字留下足够的容量。 因此，最佳位置是 1。前缀是`4`，变化后的数字为`7`，其余计数需要一个 4 和一个 7，给出`4747`。 这与官方示例相符。 

对于第二个样本，`n = 47`，长度是2，一半是1。两个数字都很幸运，它们的计数已经相等。 

| 职位| 数字| 阅读后 4 秒 | 阅读后 7 秒 | 状态 |
 | ---| ---| ---| ---| ---|
 | 0 | 4 | 1 | 0 | 前缀仍然有效 |
 | 1 | 7 | 1 | 1 | 完全平衡|

 由于输入本身满足每个条件，因此算法返回`47`无需构建更大的候选者。 这说明了为什么在应用严格增加贪婪步骤之前必须检查相等情况。

    return solve(sys.stdin.readline().strip()) + '\n'

 ## 边缘情况

 对于奇数长度的情况，考虑精确的输入`1`。 它的长度是1，所以4和7的数量不可能相同。 该算法立即将目标长度更改为 2，并构造一个 4，后跟一个 7。输出为`47`，这是可能的最小超级幸运数字并且大于`1`。 

对于已经非常幸运的输入，请考虑`47`。 该算法计算一个 4 和一个 7，匹配这两个数字所需的半长 1。 它返回未更改的输入。 这可以防止贪婪构造不必要地使答案变大。 

对于可以直接替换的无效数字，请考虑`4500`。 在位置0处，将4改为7是可行的，所以`best_pos`变为0。在位置1处，数字5可以用7代替，而前缀`4`仍然有效，并且仍然可以完成数字计数。 由于位置 1 较晚，因此它取代了先前的候选者。 后缀需要一个 4 和一个 7，产生`4747`。 

对于太大而无法直接替换的无效数字，请考虑`4788`。 在位置0处，将4改为7是可行的。 在第一个无效数字之后不能使用位置 1 及更高位置，因为未更改的前缀将包含 8。该算法将候选者保留在位置 0，给出前缀 ``, changed digit `7`, and a suffix containing one 4 and one 7, so the result is `7447`. This is larger than `4788` 是最小的有效四位数候选值。 

对于每个相同长度候选者都不可能的情况，请考虑`7777`。 长度为 4，因此有效答案需要两个 4 和两个 7。 没有一个包含4的位置可以增加，更早的7是不可能改变的，因为7已经是最大的幸运数字。 没有记录候选者，因此算法移动到长度 6。最小的六位超级幸运数字是`444777`，它必然大于每个四位数，因此是正确答案。
