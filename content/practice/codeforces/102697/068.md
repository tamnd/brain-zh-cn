 ## 解决方案
 ## 问题理解

 我们得到了按时间顺序排列的 (N) 个历史价格序列。 对于每对连续测量，价格要么上涨、下跌，要么保持不变。 RSI计算只关心上涨和下跌。 

对于每次增加，我们都会收集该增加的规模。 对于每次减少，我们都会收集该减少的绝对大小。 然后我们计算所有增加的算术平均值，称为`aveUP`，以及所有减少的算术平均值，称为`aveDOWN`。 所需的值为

 [
 RS = \frac{aveUP}{aveDOWN}
 ]

 随后

 [
 RSI = 100-\frac{100}{RS+1}。 
]

 官方声明指定了 1 秒的时间限制和 256 MB 的内存，但没有公布 (N) 的数值上限。 这使得线性方法成为自然的目标：每个价格只需要与它的前一个价格进行一次比较。 二次算法将执行大约 (N^2) 的工作，并且随着输入的增长而变得不切实际，而 (O(N)) 扫描对于非常大的序列仍然易于管理。 

有几个细节可以悄然改变答案。 

首先，减少必须贡献正数。 例如，```
3
10 7 9
```尺寸减小一处 (3)，尺寸增大一处 (2)。 因此`aveUP = 2`,`aveDOWN = 3`，答案是```
40.0
```粗心的实施增加了原始差异`7 - 10 = -3`向下总和将产生负平均值和无效 RSI。 

其次，价格不变对这两个平均值都没有贡献。 例如，```
4
10 10 12 9
```(2) 增加 1 次，(3) 减少 1 次，所以答案又是```
40.0
```将不变的货币对视为增加或减少会扭曲其中一个平均值。 

第三个问题是平均值是针对其各自类型的变化，而不是针对所有 (N-1) 个相邻对。 在样本中，```
4
6500.0 6510.0 6300.0 6200.0
```(10)增加一次，(210)和(100)减少两次。 因此`aveUP = 10`,`aveDOWN = 155`，给出所需的输出`6.060606060606062`。 如果始终如一地进行，将两个总和除以 (N-1=3) 恰好会取消，但单独计算向上和向下的变化可以使预期的公式明确，并避免实现时出现错误。 

该语句还保证历史记录至少包含一次增加和至少一次减少，因此定义了两个平均值并且`aveDOWN`不能为零。 

## 方法

 直接的强力解释可以在每次需要平均值时重新计算完整的变化集。 对于每个 (N-1) 个相邻位置，这样的实现可以再次扫描所有 (N-1) 个相邻对，对每个差异进行分类，并重建向上和向下的总和。 它是正确的，因为每次扫描都会准确地重建公式所需的信息，但在最坏的情况下它会执行 ((N-1)^2) 对检查。 对于(N)个价格，即(N^2-2N+1)次检查，这是不必要的工作。 

暴力方法会失败，因为相邻的差异是独立的。 一旦我们检查了这对`(prices[i-1], prices[i])`，它对最终平均值的贡献永远不会改变。 没有理由再次检查这一对。 

关键的观察结果是，RSI 公式仅取决于正变化的总和和计数以及负变化的总和和计数。 我们可以在扫描一次价格的同时准确地维护这四个数量。 对于正差值，将其添加到向上总和并增加向上计数。 对于负差，将其绝对值添加到向下总和中并增加向下计数。 零差异将被忽略。 

扫描后，平均值就是相应的总和除以计数。 其余的计算是常数时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(N^2)) | (O(1)) | (O(1)) | 对于大 (N) 来说太慢 |
 | 最佳 | (O(N)) | (O(1)) 额外 | 已接受 |

 ## 算法演练

 1. 读取价格数量和价格顺序。 价格已按时间顺序排序，因此只需比较连续的值。 
2. 初始化`up_sum`,`up_count`,`down_sum`， 和`down_count`为零。 这些变量恰好包含稍后构建两个平均值所需的信息。 
3. 对于每对连续价格，计算`change = current - previous`。 如果变化是积极的，将其添加到`up_sum`并增加`up_count`。 如果变化为负，则添加`-change`到`down_sum`并增加`down_count`。 如果变化为零，则不执行任何操作。 

使用`-change`因为负变化相当于取其绝对值，同时避免有关向下贡献的符号的任何模糊性。 
4. 计算

 [
 aveUP = \frac{up_sum}{up_count}
 ]

 和

 [
 aveDOWN = \frac{down_sum}{down_count}。 
]

 该问题保证两个计数都不为零，因此这些除法是有效的。 
5. 计算相对强度

 [
 RS=\frac{aveUP}{aveDOWN}。 
]

 然后代入RSI公式：

 [
 RSI=100-\frac{100}{RS+1}。 
]
 6. 打印生成的浮点值。 Python 的标准浮点表示足以满足此计算。 

整个扫描过程中不变的是，在处理第一个 (i) 价格之后，`up_sum`和`up_count`准确描述这些价格之间的所有积极变化，同时`down_sum`和`down_count`准确地描述所有负面变化的积极程度。 每个相邻对都被处理一次并准确地放入适当的类别中，因此在最后对之后，四个累加值精确地表示 RSI 定义所使用的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    prices = list(map(float, input().split()))

    up_sum = 0.0
    up_count = 0
    down_sum = 0.0
    down_count = 0

    for i in range(1, n):
        change = prices[i] - prices[i - 1]

        if change > 0:
            up_sum += change
            up_count += 1
        elif change < 0:
            down_sum += -change
            down_count += 1

    ave_up = up_sum / up_count
    ave_down = down_sum / down_count

    rs = ave_up / ave_down
    rsi = 100.0 - 100.0 / (rs + 1.0)

    print(rsi)

if __name__ == "__main__":
    solve()
```输入被读取为浮点数，因为价格本身可以包含小数值。 第一个价格没有前导，因此循环故意从索引处开始`1`。 这避免了在第一次测量之前进行比较的常见误差。 

对于每个后续价格，`change`准确地代表了价格历史中的一次变动。 正值更新向上统计数据，负值使用其正值更新向下统计数据，零值不更新统计数据。 

仅在完整扫描后计算平均值。 不需要存储单独的增加或减少，因此该算法使用除输入数组之外的恒定额外空间。 Python 整数可以增长而不会溢出，并且这里的总和是浮点值，因为输入价格是浮点的。 

最终操作的顺序直接遵循定义。 首先形成两个平均值，然后计算它们的比率，然后将该比率代入 RSI 表达式。 该问题保证了增加和减少，因此平均值都不需要特殊的零计数情况。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O(N)) | 每个 (N-1) 个相邻价格对都被处理一次。 |
 | 空间| (O(N)) | 存储输入价格数组； 算法本身使用 (O(1)) 额外空间。 |

 已发布的声明给出了 1 秒限制和 256 MB 内存，同时省略了 (N) 的数值上限。 无论缺失边界如何，单个线性扫描都是适当的复杂度。 该实现仅对每个价格执行恒定的工作，并使用超出输入数组的固定数量的累加器。

    up_sum = 0.0
    up_count = 0
    down_sum = 0.0
    down_count = 0

            up_count += 1
        elif change < 0:
            down_sum += -change
            down_count += 1

    ave_up = up_sum / up_count
    ave_down = down_sum / down_count

    rs = ave_up / ave_down
    rsi = 100.0 - 100.0 / (rs + 1.0)

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        return solve()
    finally:
        sys.stdin = old_stdin
        input = old_input

## 边缘情况

 对于负向运动，算法显式添加`-change`而不是`change`。 在```
3
10 7 9
```第一个区别是`-3`， 所以`down_sum`变成`3`， 不是`-3`。 第二个区别是`+2`， 所以`up_sum`变成`2`。 平均值是`2`和`3`, 给予`RS = 2/3`和`RSI = 40.0`。 这直接处理语句中的符号要求。 

对于不变的价格，请考虑```
4
10 10 12 9
```第一个差异为零并且被忽略。 下一个区别是`+2`，最终的差异是`-3`。 累计值是`up_sum = 2`,`up_count = 1`,`down_sum = 3`， 和`down_count = 1`, 生产`40.0`。 零运动绝不属于任何一个平均值。 

对于第一个价格，请考虑```
3
10 11 10
```循环从第二个价格开始，因此比较是`11 - 10`和`10 - 11`。 没有尝试将第一个价格与不存在的前任进行比较。 向上和向下的平均值分别是`1`和`1`, 给予`RS = 1`和`RSI = 50.0`。 

对于分数价格，请考虑```
4
1.5 2.5 2.5 1.0
```变化是`+1.0`,`0.0`， 和`-1.5`。 零被忽略，给出`aveUP = 1.0`和`aveDOWN = 1.5`。 由此产生的 RSI 为`40.0`。 读取价格为`float`值是必要的，因为明确允许输入包含浮点测量值。 

最后，该算法依赖于问题保证至少一个价格上涨和至少一个价格下降。 这意味着`up_count > 0`和`down_count > 0`扫描后，因此可以安全地计算两个平均值，而无需人为处理除零。
