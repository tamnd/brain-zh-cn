 ## 解决方案
 ## 问题理解

 我们得到了一个完整的 9 x 9 数独网格。 每个单元格都包含一个整数，任务是确定网格是否遵守三个数独唯一性规则：一个数字不能在一行中出现两次，在一列中出现两次，或者在同一个 3 x 3 框中出现两次。 所需的输出是`VALID`当所有三个条件成立并且`INVALID`否则。 最初的问题将棋盘尺寸固定为 9 x 9，并保证输入值是从 1 到 9 的整数。 

由于电路板尺寸永远不会增长，因此整个输入仅包含 81 个单元。 这改变了我们对复杂性的思考方式。 即使是对每对细胞进行多次比较的解决方案，从绝对值来看也是很小的。 干净的线性扫描仍然更可取，因为它直接表示数独规则并且索引错误的机会较少，但不存在需要高级数据结构的大型隐藏约束。 这两种方法都很容易满足一秒的限制。 

存在三种常见的正确性陷阱。 首先，仅检查行是不够的。 例如，```
1 2 3 4 5 6 7 8 9
1 2 3 4 5 6 7 8 9
4 5 6 7 8 9 1 2 3
2 3 1 5 6 4 8 9 7
5 6 4 8 9 7 2 3 1
8 9 7 2 3 1 5 6 4
3 1 2 6 4 5 9 7 8
6 4 5 9 7 8 3 1 2
9 7 8 3 1 2 6 4 5
```有正确的输出`INVALID`。 仅验证每行内容的粗心实现会接受它，即使第一列包含两个`1`s。 

其次，检查行和列仍然漏掉了 3 x 3 框。 考虑一个网格，其中两个相等的值占据不同的行和不同的列，但共享一个框。 例如，左上角的框可以开头为```
1 2 3
4 1 6
7 8 9
```两人`1`s 不在同一行或列，但它们违反了盒子规则，因此完整的板必须报告为`INVALID`。 仅检查行和列的实现静默接受此配置。 

第三，框索引必须同时使用行组和列组。 对于一个细胞`(r, c)`，正确的框由下式确定`r // 3`和`c // 3`。 仅使用`r // 3`例如，将三个框合并在同一水平带中，并且可能会拒绝有效的板或无法检测到目标框中的重复项。 

## 方法

 最直接的强力验证器会检查每一行、每一列和每个 3 x 3 框。 对于每组九个单元格，它可以比较每一对单元格，如果两个值相等则拒绝该板。 总共有27组，每组有`C(9, 2) = 36`成对，所以最坏的情况执行完全`27 * 36 = 972`除了枚举组所需的少量索引之外，还需要进行配对比较。 对于固定的 9 x 9 板来说，这绝对足够快，因此对于这个问题来说，暴力破解实际上并不算太慢。 

更简洁的方法是处理每个单元格一次，并记住哪些数字已经出现在其行、列和框中。 对于每个包含数字的单元格`x`，我们同时问三个问题：有`x`出现在这一行中，出现在这一列中，出现在这个 3 x 3 框中吗？ 如果任何一个答案是肯定的，则该董事会无效。 否则我们标记`x`存在于所有三个地方并继续。 

关键的观察结果是，三个数独规则都是同一属性的实例：在特定组内，每个数字最多可能出现一次。 由于只有九个可能的数字，因此一个小的布尔数组足以表示每个组的状态。 我们不需要将当前单元格与所有先前的单元格进行比较。 

由此产生的方法恰好接触 81 个细胞，并对每个细胞执行恒定的工作。 它比成对方法更简单，同时如果电路板尺寸增加，它也是自然的概括。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(81²)，固定板有 972 对比较 | O(1) | O(1) | 已接受 |
 | 最佳 | O(81) | O(1) | O(1) | 已接受 |

 这里`O(81)`从技术上来说是`O(1)`因为问题修复了电路板尺寸，但将其写为`O(81)`让工作量更加清晰。 

## 算法演练

 1. 创建三个 9 × 9 布尔结构，名为`rows`,`cols`， 和`boxes`。`rows[r][d]`记录是否为数字`d`已出现在行中`r`,`cols[c][d]`对列做同样的事情`c`， 和`boxes[b][d]`对盒子做同样的事情`b`。 使用单独的结构反映了三个独立的数独约束。 
2. 从第一行到最后一行、从第一列到最后一列扫描网格。 对于当前单元格`(r, c)`，读取其数字并将其转换为从零开始的索引，例如`digit - 1`。 
3. 计算包含单元格的 3 x 3 框```
box = (r // 3) * 3 + (c // 3)
```表达式`r // 3`给出盒子的水平带，而`c // 3`给出它在该带内的位置。 将第一部分乘以 3 可将该对转换为从 0 到 8 的一个索引。 

1. 在标记任何内容之前，请检查`rows[r][digit]`,`cols[c][digit]`， 和`boxes[box][digit]`。 如果任何一个已经为真，则相同的数字在所需组之一中出现了两次，因此立即打印`INVALID`。 
2. 如果所有三项检查均不正确，则将该数字标记为当前行、列和框中存在的数字。 任何这些组中的未来细胞都会检测到这种情况的发生。 
3. 处理完所有 81 个单元格且未发现冲突后，打印`VALID`。 由于每个单元格都针对所有三个相关组进行了检查，因此不可能违反任何数独规则。 

不变的是，在处理网格的任何前缀后，每个布尔结构准确地记录了该前缀内相应行、列和框中出现的数字。 当遇到重复项时，相应的布尔值已经为真，证明棋盘违反了规则。 如果没有发现重复，则每个处理组中每个数字最多包含一次，并且在处理完所有 81 个单元格后，整个棋盘有效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    board = [list(map(int, input().split())) for _ in range(9)]

    rows = [[False] * 9 for _ in range(9)]
    cols = [[False] * 9 for _ in range(9)]
    boxes = [[False] * 9 for _ in range(9)]

    for r in range(9):
        for c in range(9):
            value = board[r][c]

            # The official input guarantees values from 1 to 9,
            # but keeping this check makes the validator complete.
            if not 1 <= value <= 9:
                print("INVALID")
                return

            digit = value - 1
            box = (r // 3) * 3 + (c // 3)

            if rows[r][digit] or cols[c][digit] or boxes[box][digit]:
                print("INVALID")
                return

            rows[r][digit] = True
            cols[c][digit] = True
            boxes[box][digit] = True

    print("VALID")

if __name__ == "__main__":
    solve()
```棋盘被解读为九个列表，每个列表包含九个整数。 这三个布尔数组代表第一个算法步骤中描述的状态。 从零开始的数字索引很方便，因为 Python 数组使用从 0 到 8 的索引，因此值`1`映射到索引`0`和价值`9`映射到索引`8`。 

盒子计算是实现中最容易出错的表达式。 例如，细胞`(0, 0)`属于盒子`0`， 细胞`(2, 2)`也属于盒子`0`， 细胞`(0, 3)`属于盒子`1`，和细胞`(6, 6)`属于盒子`8`。 两个整数除法都是必要的。 

在设置三个布尔条目之前必须进行重复检查。 如果当前值已经出现，则其中一项为真，并且该板将立即被拒绝。 如果我们先标记然后检查，当前单元格看起来总是像其自身的副本。 

不存在整数溢出问题，因为每个索引和值都很小。 在官方输入保证下，显式范围检查在技术上是多余的，但它直接实现了规定的数字要求，并使验证器对格式错误的输入具有鲁棒性。

 ## 边缘情况

 第一个边缘情况是仅出现在列中的重复情况。 在`column_duplicate`，最后一行从另一行开始`1`，而该行本身包含不同的值。 当算法达到`(8, 0)`,`rows[8][0]`是假的，但是`cols[0][0]`已经为真，因为第一行包含`1`在那一栏里。 算法打印`INVALID`。 这捕获了验证行但忘记列的实现。 

第二个边缘情况是限制在 3 x 3 盒子中的重复情况。 在左上角的框中`box_duplicate`，值`1`出现在`(0, 0)`和`(1, 1)`。 这些单元格具有不同的行和不同的列，因此单独的行和列检查不会拒绝它们。 为了`(1, 1)`，计算出的框是`(1 // 3) * 3 + (1 // 3) = 0`， 和`boxes[0][0]`已经是真的了。 输出是`INVALID`。 这是验证盒子公式的关键情况。 

第三种边缘情况是一个有效的棋盘，其值恰好跨越框边界。 在`boundary_valid`，扫描跨越第 2 列和第 3 列、第 2 行和第 3 行以及第 5 行和第 6 行以及第 5 行和第 6 列的后续边界。整数除法精确地更改了这些边界处的框索引。 在其行、列或框中没有重复的数字，因此每个检查都保持错误，最终输出为`VALID`。 这捕获了使用错误的盒子分区的常见差一错误。 

样本 2 中的所有平等情况都执行了最早可能的失败。 处理完第一条后`1`，第 0 行中的第二个单元格查找已设置的行标志和框标志。 该算法在两个单元格后停止并打印`INVALID`。 这说明了为什么在更新之前必须检查状态，以及为什么一旦发现违规，提前返回是安全的。
