 ## 解决方案
 ## 问题理解

 任务是使用 Morbit 密码对小写明文进行加密。 加密中间有两种表示形式：莫尔斯电码和两个字符的莫尔斯码块。 

每个字母都被替换为其标准莫尔斯电码表示形式。 在连续的字母之间我们放置一个`x`，而在连续的单词之间我们放置两个`x`人物。 因此`ab`变成`.-x-...`， 因为`a`是`.-`，字母之间用`x`， 和`b`是`-...`。 然后，完整的莫尔斯字符串从左到右分成两对。 如果它的长度是奇数，则最后一个`x`已附加。 

正好有九个可能的对，因为每个位置都可以包含`.`,`-`， 或者`x`。 九个关键行给出了这九对的排列。 第一行是数字代表的对`1`，第二个是数字代表的对`2`，依此类推通过数字`9`。 所需的输出是与构造的莫尔斯字符串中每个连续对相对应的数字。 官方声明指定了 1 秒的时间限制和 256 MB 的内存限制。 

该语句没有提供明确的最大明文长度。 这意味着安全设计是对文本的单一线性传递，而不是任何工作量呈二次方增长的东西。 由于键仅包含九个条目，因此即使对所有九个条目进行简单查找也会受到一个非常小的常量的限制，但字典可以提供更清晰的结果`O(1)`查找每对莫尔斯电码。 

第一个边缘情况是莫尔斯电码表示形式具有奇数长度的明文。 例如，使用密钥```
xx
.-
-.
x.
.x
..
--
-x
x-
```输入```
e
xx
.-
-.
x.
.x
..
--
-x
x-
```有摩尔斯电码`.`。 必须将其填充到`.x`，映射到`5`，所以输出是`5`。 只处理完整对的粗心实现会丢失最终字符。 

第二个边缘情况是字边界。 使用相同的密钥，明文`ab`产生`.-x-...`。 它的对是`.-`,`x-`,`-.`， 和`..`, 给予`2936`。 一个常见的错误是使用一个`x`一个空间，但一个空间需要两个`x`人物。 边界之后的每一对的区别都会发生变化。 该问题明确定义了一个`x`字母之间和两个单词之间。 

第三种边缘情况是一个单字母单词，其莫尔斯电码表示本身的长度为一。 例如，`e`简直就是`.`，所以需要填充规则。 结果对是`.x`，不仅仅是`.`。 

## 方法

 直接方法可以首先构造完整的莫尔斯电码字符串，然后一次处理两个字符。 对于每一对，我们可以扫描九个关键条目，直到找到匹配的对。 这是正确的，因为密钥准确定义了哪个数字代表每个可能的两个字符块。 如果莫尔斯字符串包含`P`字符，有`P / 2`对，每次查找最多可以检查九个条目，最多给出`9P / 2`配对比较。 该问题没有规定最大值`P`，因此即使常数很小，重复扫描密钥也是不必要的工作。 

使更清晰的解决方案立即产生的观察结果是密钥是固定的并且仅包含九个可能的对值。 我们可以通过存储反转密钥一次`pair -> digit`。 然后，通过一次字典查找将每个莫尔斯电码对转换为其数字。 昂贵的部分不再是搜索密钥，因此整个加密过程与生成的莫尔斯字符串的大小成线性关系。 

莫尔斯转换本身也是线性的。 我们将每个明文字母通过一个固定的26条目表进行映射，插入`x`当一个字母后面跟着另一个字母时，然后插入`xx`当下一个字符开始另一个单词时。 构建莫尔斯表示后，填充和配对处理各自进行另一次线性传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(9P) | O(P)| 接受适度的输入，但不必要的重复查找 |
 | 最佳| O(P)| O(P)| 已接受 |

 这里`P`表示生成的莫尔斯字符串的长度，包括分隔符和可能的填充。 由于每个莫尔斯编码的长度最多为四个，并且每个字母仅提供恒定数量的分隔符信息，`P`与明文长度成线性关系。 

## 算法演练

 1. 读取完整的明文行，不丢弃空格。 这些空间是有意义的，因为它们决定了两个`x`必须插入字符。 
2. 读取九个密钥对，并创建一个字典，其密钥为两字符块，其值为其数字`1`通过`9`。 这会反转密钥的给出方向，从而完全匹配加密所需的内容。 
3. 将明文转换为摩尔斯电码。 对于每个单词，使用标准 A 到 Z 莫尔斯表转换其字母，并放入一个`x`连续字母之间。 放两个`x`连续单词之间的字符。 
4. 如果生成的莫尔斯字符串长度为奇数，则追加 1`x`。 这使得每个字符都属于一个两字符块。 
5. 以两步遍历莫尔斯字符串。 提取每一对并在密钥字典中查找。 将相应的数字附加到答案中。 
6. 将累积的数字作为一个字符串打印。 每对仅贡献一位数字，因此输出中不包含任何分隔符。 

**为什么有效。** 经过莫尔斯转换后，构造的字符串正是密码所需的中间表示形式，因为字母使用其莫尔斯电码，而单词和字母边界使用指定的`x`分隔符。 填充仅更改所需的最终不匹配位置，并且在长度为奇数时精确执行。 然后，该字符串被划分为由密码定义的相同的连续两个字符块。 逆键字典将每个这样的块精确地映射到分配给它的数字，因此每个输出数字都是正确的，并且每个块都被处理一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MORSE = [
    ".-", "-...", "-.-.", "-..", ".", "..-.", "--.", "....", "..",
    ".---", "-.-", ".-..", "--", "-.", "---", ".--.", "--.-", ".-.",
    "...", "-", "..-", "...-", ".--", "-..-", "-.--", "--.."
]

def solve():
    text = input().rstrip("\n")

    key = {}
    for digit in range(1, 10):
        pair = input().strip()
        key[pair] = str(digit)

    words = text.split()
    morse_parts = []

    for word_index, word in enumerate(words):
        for i, ch in enumerate(word):
            morse_parts.append(MORSE[ord(ch) - ord("a")])
            if i + 1 < len(word):
                morse_parts.append("x")

        if word_index + 1 < len(words):
            morse_parts.append("xx")

    morse = "".join(morse_parts)

    if len(morse) % 2:
        morse += "x"

    answer = []
    for i in range(0, len(morse), 2):
        answer.append(key[morse[i:i + 2]])

    print("".join(answer))

if __name__ == "__main__":
    solve()
```这`MORSE`数组索引为`ord(ch) - ord("a")`， 所以`a`选择索引`0`,`b`选择索引`1`，等等。 这避免了条件语句链并提供恒定时间的字母转换。 

将明文分割成单词，以便可以准确地表示单词边界`xx`。 在每个单词中，代码显式插入一个`x`仅在两个字母之间。 这可以避免在单词的最后一个字母后意外添加分隔符。 

键字典是按照与输入相反的方向构建的。 如果第五行关键行是`.x`， 然后`key[".x"]`变成`"5"`。 这是加密时所需的查找方向。 

仅在构建整个莫尔斯字符串后才进行填充。 这个顺序很重要，因为最后的`x`是填充，而不是单词分隔符。 以字边界结尾的明文不应获得额外的人为分隔符。 

对循环前进两个字符，因此用于形成一个查找键的两个字符永远不会与下一对重叠。 此循环之前的奇数长度检查保证最终切片始终恰好有两个字符。 

Python 整数在这里不会产生任何溢出问题，并且输出会累积为字符串，因为密文是数字序列而不是数字。 

## 工作示例

 使用第一个示例，密钥开头为`xx -> 1`,`.- -> 2`,`-. -> 3`,`x. -> 4`,`.x -> 5`,`.. -> 6`,`-- -> 7`,`-x -> 8`， 和`x- -> 9`。 

明文的开头是`we hope`。 这个词`we`变成`.--x.`词边界贡献`xx`，所以莫尔斯流的开头是`.--x.xx...`。 第一对是`. -`,`- x`,`. x`,`x .`，给出前四个密文数字`2`,`8`,`5`,`4`。 

| 莫尔斯位置 | 配对| 数字| 迄今为止的输出 |

 | 0 |`.-`|`2`|`2`|
 | 2 |`-x`|`8`|`28`|
 | 4 |`.x`|`5`|`285`|
 | 6 |`x.`|`4`|`2854`|

对于较小的跟踪，请考虑九对排序为的键`xx`,`.-`,`-.`,`x.`,`.x`,`..`,`--`,`-x`,`x-`，和明文`ab`。 

莫尔斯电码的表示形式是`.-x-...`。 它的长度是八，所以不需要填充。 这些对是`.-`,`x-`,`-.`， 和`..`。 

| 莫尔斯位置 | 配对| 数字| 迄今为止的输出 |
 | ---| ---| ---| ---|

 此跟踪说明了为什么在配对之前必须包含字母分隔符。 如果省略分隔符，莫尔斯码流将以不同方式分组，结果将不代表莫比特加密。
