 ## 解决方案
 ## 问题理解

 给定一个复合整数 (n)。 (n) 大于 (1) 的每个除数必须恰好绕圆放置一次。 我们可以自由选择它们的初始循环顺序。 

选择该顺序后，一个操作采用两个相邻的数字 (a) 和 (b)，计算它们的最小公倍数，并将其插入它们之间。 当每个相邻对的公约数大于 (1) 时，该圆被视为已解密。 

任务是最小化此类插入的数量并输出达到该最小值的初始排序。 

中心观察是除数的实际值并不重要，重要的是它们包含哪些不同的质因数。 假设

 [
 n=p_1^{e_1}p_2^{e_2}\cdots p_k^{e_k}。 
]

 对于每个除数 (d>1)，定义一个 (k) 位掩码。 位 (i) 在 (p_i\mid d) 时准确设置。 当两个除数的掩码具有至少一个公共设置位时，它们恰好是非互质的。 

官方给出的约束为(4\le n\le 10^9)，最多有(100)个测试用例，总共最多有(2\cdot10^5)个除数。 因此，通过试除法进行因式分解是很便宜的，因为 (\sqrt n\le31623)。 更重要的是，除数总数足够小，我们可以显式生成并存储它们。 强力排列搜索是完全不可能的，而 (O(\sqrt n+\tau(n))) 或类似的近线性构造很容易足够快。 

有几个边缘案例揭示了为什么构建需要小心。 

对于(n=4)，大于(1)的因数是(2,4)。 它们共享素因数 (2)，因此正确的最小值为零。 输出如```
2 4
0
```是有效的。 假设每个除数很少的合数都需要插入的粗心解决方案可能会错误地打印 (1)。 

对于 (n=6)，除数为 (2,3,6)。 数字(2)和(3)是互质的，并且只有一个除数同时包含两个质数，即(6)。 任何初始圆在某处都有 (2) 到 (3) 邻接，因此至少需要插入一次。 正确的最小值是 1，例如```
2 3 6
1
```对于 (n=12=2^2\cdot3)，即使有两个不同的质因数，答案也已经为零。 一个有效的订单是```
2 6 3 12 4
0
```每个相邻对都有一个公因子，包括循环对 (4,2)。 一条天真的规则“两个不同的质因数意味着一次运算”在这里悄然失败了。 这种情况起作用的原因是，至少有两个除数包含两个素数，即 (6) 和 (12)，因此它们可以将圆周围仅包含 (2) 和仅包含 (3) 的组分开。 

对于 (n=30=2\cdot3\cdot5)，三个素因数的每个非空子集都作为某个除数的素因​​数掩码出现。 合适的排序可以使每个相邻对共享一个素数，因此最小值为零。 这是位掩码构造变得特别有用的第一种情况。 

## 方法

 最直接的强力方法是生成大于 (1) 的除数的每个排列，并且对于每个排列检查所有相邻对，包括最后一个和第一个元素。 如果每对的 gcd 都大于 (1)，我们就有一个零运算解。 否则，我们可以搜索具有尽可能少的坏对的排列，因为每个坏对都可以通过插入其最小公倍数来修复。 

蛮力是正确的，因为它明确地考虑了每个可能的初始圆。 问题是排列的阶乘数。 令 (\tau(n)) 为 (n) 的约数个数，包括 (1)。 有 (\tau(n)-1) 个数字需要排列。 即使我们只检查是否存在零操作安排，最坏情况下的 gcd 检查次数也大致为

 [
 (\tau(n)-1)\cdot(\tau(n)-1)!.
 ]

 对于 (n\le10^9)，最大除数计数为 1344，例如通过 (931170240) 获得。 这使得暴力搜索需要大约 (1343\cdot1343!) gcd 计算，这根本不可行。 

有用的结构在分解 (n) 之后出现。 除数不需要用其完整的指数向量来表示。 对于互质条件，我们只关心每个不同的素数是否至少出现一次。 

这将每个除数变成不同质因数的非空子集。 如果两个掩码相交，则它们对应的约数不互质。 该问题成为小集合的非空子集上的建设性问题。 

当至少有三个不同的素数时，我们可以使用修改后的二进制格雷码对所有非空掩码进行排序。 连续的格雷码掩码恰好有一位不同，因此除了人工零掩码边界之外，任何两个连续的非空掩码共享至少一个设置位。 我们删除该边界并反转从全 1 掩码开始的后缀。 然后全一掩码成为最终掩码，而第一个掩码是包含第一个素数的单例。 这两个蒙版也相交，闭合圆圈。 

两个不同素数的情况需要单独处理。 写出(n=p^aq^b)。 每个除数都属于三组之一：仅包含 (p) 的除数、同时包含 (p) 和 (q) 的除数以及仅包含 (q) 的除数。 如果(a=b=1)，则中间组中正好有一个除数(pq)，并且一次运算是不可避免的。 如果至少有一个指数大于一，则至少有两个混因数。 我们可以在一侧的仅 (p) 组和仅 (q) 组之间放置一个混合块，并在另一侧放置另一个混合块。 这提供了零操作。 

当只有一个不同的素数时，每个除数都是该素数的幂，因此每一对都自动非互质，答案为零。 

比较结果为：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(\tau(n)\cdot\tau(n)!)) | (O(\tau(n))) | 太慢了 |
 | 因式分解+掩模构造| (O(\sqrt n+\tau(n)+2^k)) | (O(\tau(n)+2^k)) | 已接受 |

 这里 (k) 是不同质因数的数量。 由于 (n\le10^9)、(k\le9)，所以 (2^k\le512)。 

## 算法演练

1. 将 (n) 分解为其不同素因子 (p_0,p_1,\ldots,p_{k-1}) 及其指数。 试除法就足够了，因为 (n) 最多为 (10^9)。 
2. 生成每个大于 (1) 的除数。 同时，计算其素数存在掩模。 当除数中(p_i)的指数为正时，设置位(i)。 将除数存储在相应的掩码组中。 
3. 如果 (k=1)，则连接该组中的所有除数并输出零运算。 每个除数都包含唯一的素因数。 
4.如果(k=2)，则调用组(P)、(M)和(Q)，对应于掩码(01)、(11)和(10)。 如果 (M) 包含至少两个除数，则将其分成两个非空部分并输出

 [
 P,\M_1,\Q,\M_2。 
]

 每个边界都位于共享 (p) 或 (q) 的数字之间，并且从 (M_2) 回到 (P) 的圆形边界也共享 (p)。 
5. 如果 (k=2) 和 (M) 仅包含一个除数，则两个指数都必须为 1，因此 (n=pq)。 以任意顺序输出三组。 在仅 (p) 的除数和仅 (q) 的除数之间，恰好存在一个不良邻接。 在那里插入它们的最小公倍数，即 (n)。 最小值恰好是 1。 
6. 如果(k\ge3)，构造普通二进制格雷码序列

 [
 G_i=i\oplus(i\mathbin{>>}1)
 ]

 对于 (0\le i<2^k)。 找到全 1 掩码 (2^k-1)。 
7. 删除初始零掩码并反转从全一掩码开始的后缀。 按顺序访问生成的掩码并附加属于每个掩码的每个除数。 
8. 输出清零操作。 从格雷码继承的连续掩码有一位不同，因此两个掩码都包含至少一个公共质数。 反转后缀不会更改该后缀内相邻的掩码，而将全 1 掩码移动到末尾会使圆形边界将全 1 掩码连接到初始单例掩码。 

### 为什么它有效

 不变的是，每当两个连续的蒙版组彼此相邻放置时，它们的蒙版就会相交。 一组内的所有约数都具有完全相同的一组不同质因数，因此一组内的约数自动是非互质的。 对于 (k\ge3)，格雷码邻接保证每个普通相邻对的交集，并且最终的全 1 掩码与第一个单例掩码相交，因此循环对也是有效的。 对于两个素数，分割混合群明确地在纯群的两侧提供混合除数。 不能以这种方式分离两个素数的唯一情况是 (n=pq)，其中唯一混合除数不能占据两侧，因此需要一次操作。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def factorize(n):
    factors = []

    if n % 2 == 0:
        e = 0
        while n % 2 == 0:
            n //= 2
            e += 1
        factors.append((2, e))

    p = 3
    while p * p <= n:
        if n % p == 0:
            e = 0
            while n % p == 0:
                n //= p
                e += 1
            factors.append((p, e))
        p += 2

    if n > 1:
        factors.append((n, 1))

    return factors

def solve_case(n):
    factors = factorize(n)
    k = len(factors)

    groups = [[] for _ in range(1 << k)]

    def generate(i, value, mask):
        if i == k:
            if value > 1:
                groups[mask].append(value)
            return

        p, e = factors[i]

        generate(i + 1, value, mask)

        cur = value
        for _ in range(e):
            cur *= p
            generate(i + 1, cur, mask | (1 << i))

    generate(0, 1, 0)

    if k == 1:
        order = groups[1]
        return order, 0

    if k == 2:
        pure_p = groups[1]
        mixed = groups[3]
        pure_q = groups[2]

        if len(mixed) == 1:
            order = pure_p + mixed + pure_q
            return order, 1

        cut = len(mixed) // 2
        left_mixed = mixed[:cut]
        right_mixed = mixed[cut:]

        order = pure_p + left_mixed + pure_q + right_mixed
        return order, 0

    total_masks = 1 << k
    gray = [i ^ (i >> 1) for i in range(total_masks)]
    full = total_masks - 1

    pos = gray.index(full)

    mask_order = gray[1:pos] + list(reversed(gray[pos:]))

    order = []
    for mask in mask_order:
        order.extend(groups[mask])

    return order, 0

def solve_all(numbers):
    output = []

    for n in numbers:
        order, moves = solve_case(n)
        output.append(" ".join(map(str, order)))
        output.append(str(moves))

    return "\n".join(output)

def main():
    t = int(input())
    numbers = [int(input()) for _ in range(t)]
    sys.stdout.write(solve_all(numbers))

if __name__ == "__main__":
    main()
```因式分解例程首先删除因子 (2)，然后测试奇数候选项直至剩余数字的平方根。 一旦循环后剩余的值大于1，它必然是质数，成为最终的因子。 

递归除数生成器为每个不同的素数选择一个指数。 指数为零的递归分支未设置掩码位，而每个正指数设置相应位。 这意味着每个除数只生成一次，并立即放入由其素数存在掩码确定的组中。 

除了输出其组之外，单素数情况不需要任何构造。 每个除数都是同一个素数的正幂。 

对于两个素数，`mixed`群包含每个可被两个素数整除的除数。 它的大小是两个指数的乘积。 因此，当两个指数都为 1 时，它就是 1。 在这种特殊情况下，答案是一个。 否则，至少有两个混合约数，因此可以将组分成两个非空部分。 

对于至少三个素数，`gray`每个掩码都包含一次。 零掩码被排除，因为问题排除了除数 (1)。 通过反转适当的后缀，将全 1 掩码移至末尾。 这是关键的边界操作。 如果没有它，第一个和最后一个非零灰色蒙版可能会不相交，这将使圆形对无效。 

Python 整数不会溢出，并且每个生成的除数最多为 (n)。 递归深度最多为不同质因数的数量，对于 (n\le10^9) 最多为 9，因此递归是安全的。

 ## 边缘情况

 对于 (n=4)，因式分解具有一个不同的素数，因此算法将 (2) 和 (4) 放入同一掩码组中。 输出是`2 4`零操作。 它们的 gcd 为 (2)，因此循环对已经有效。 

对于 (n=6)，因式分解有两个指数都等于 1 的素数。 混合组仅包含 (6)，因此算法输出仅 (2) 组、混合组和仅 (3) 组。 生成的圆恰好有一个互质边界 (3,2)。 它们的最小公倍数是 (6)，因此一次插入就固定了圆。 由于（2）和（3）必须同时出现，并且只有一个混合除数，因此不存在零运算排列。 

对于 (n=12)，组为 (P={2,4})、(M={6,12}) 和 (Q={3})。 该算法将 (M) 分成两个非空部分，并可以产生`2 6 3 12 4`。 当包含圆形边界时，连续对分别具有 gcd (2,3,3,2,2)。 因此零操作就足够了。 

对于诸如 (n=16) 之类的数字，每个大于 (1) 的除数都是 (2) 的幂。 该算法不需要格雷码或任何特殊的插入。 所有除数都属于同一个掩码，并且任何排序都有效，因为每对除数至少具有 (2) 的 gcd。 

对于 (n=30)，掩码都是三个素数的七个非空子集。 修改后的格雷码顺序为`1,3,2,6,4,5,7`。 将这些掩码转换为除数给出`2,6,3,15,5,10,30`。 每个连续的对，包括循环对 (30,2)，共享一个素因数。 因此答案为零。 

对于大压力情况 (931170240)，该数字有 1344 个除数，这是最多 (10^9) 的数字的最大除数计数。 该算法从不考虑排列。 它对数字进行因式分解，生成其除数一次，将每个除数分配给一个掩码组，并最多处理 (2^9=512) 个掩码。 这正是建设性解决方案和阶乘暴力之间的区别。
