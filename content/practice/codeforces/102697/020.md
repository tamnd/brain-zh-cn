 ## 解决方案
 ## 问题理解

 该问题要求我们构建一个非常小的加密转换。 每个输入单词代表一个字符序列，加密规则将字符成对对待。 在每个相邻对中，第一个字符在第二个字符之后移动，这与将每个奇数位置的字符与后面的偶数位置的字符交换相同。 如果该单词具有未配对的最终字符，则它保持不变。 第一个输入值告诉我们必须转换多少个单词，输出是每个转换后的单词在其自己的行上。 

主要限制是单词的长度。 由于该操作只需检查每个字符一次，因此线性解决方案是自然的目标。 任何重复搜索、重建或比较单词大部分内容的方法都会增加不必要的工作。 如果一个单词包含数十万个字符，那么比 O(length) 慢的算法可能会变得过于昂贵，因为它会对只需要一次传递的数据执行重复操作。 

棘手的情况来自靠近单词末尾的位置。 奇数字的字，有尾字，没有伙伴，所以一定不能移动。 例如，输入：```
1
ABCDE
```正确的输出是：```
BADCE
```粗心的实现将每个索引与下一个索引交换而不检查边界，可能会尝试访问之后的字符`E`并在其他语言中失败或意外修改内存。 

另一种边缘情况是单字符单词。 例如：```
1
Z
```正确的输出是：```
Z
```没有可以交换的对，因此算法必须保持字符不变。 假设每个角色都有一个伙伴的实现会产生不正确的结果。 

重复的字符也不需要特殊处理。 例如：```
1
AAAA
```正确的输出是：```
AAAA
```交换仍然会发生，但相同的角色隐藏了移动。 该算法应该依赖于位置而不是字符值。 

## 方法

 最简单的方法是完全按照描述模拟加密。 从第一个字符开始，与下一个字符交换，然后向前移动两个位置并重复。 这是正确的，因为每对受影响的对都独立于其他对。 对于一个字的长度`n`，该算法执行大约`n / 2`交换，因此运行时间为 O(n)。 

对于这个问题没有有意义的强力搜索，因为转换已经是确定性的。 较慢的实现可能会在每次交换后重复创建新字符串。 虽然在逻辑上仍然正确，但在字符串不可变的语言中执行此操作可以将每次交换变成 O(n) 复制操作。 对于一个字的长度`n`，这可能会变成 O(n²)，大致执行`n² / 2`最坏情况下的角色移动。 

关键的观察是互换不会影响未来的决策。 职位后`0`和`1`交换了位置`2`和`3`可以独立处理。 这让我们可以从左到右处理字符串，同时只更改每对一次。 构建一个可变的字符列表并在最后加入它给出了直接的 O(n) 实现。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 对于大输入来说太慢 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取每个单词并将其转换为可变的字符序列。 Python 字符串无法就地更改，因此使用列表允许交换单个字符。 
2.从索引开始`0`并一次在单词中移动两个位置。 当前索引表示一对字符中的第一个字符，下一个索引表示第二个字符。 
3. 如果下一个索引存在，则交换两个字符。 这会将加密规则应用于当前对，而不影响任何其他对。 
4. 继续，直到处理完所有对。 如果长度为奇数，则最终字符永远不会被选为完整对的第一个元素，因此它保持不变。 
5. 将字符序列连接回字符串并打印结果。 

为什么它有效：

 该算法保持了不变性，即当前位置之前的每一对都已被恰好加密一次，并且当前位置之后的每一对仍处于其原始状态。 由于加密规则仅交换每个相邻对内的字符，因此处理一对不能更改另一对的正确结果。 唯一可能的剩余字符是奇数长度单词的最后一个字符，保持其不变符合所需的转换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def transform(word):
    chars = list(word)
    i = 0
    n = len(chars)

    while i + 1 < n:
        chars[i], chars[i + 1] = chars[i + 1], chars[i]
        i += 2

    return ''.join(chars)

def main():
    t = int(input())
    ans = []

    for _ in range(t):
        word = input().strip()
        ans.append(transform(word))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    main()
```这`transform`函数包含了整个算法。 将字符串转换为列表是必要的，因为Python字符串是不可变的，而列表元素可以直接交换。 

循环条件`i + 1 < n`是保护奇数长度字的边界检查。 当最后一个字符没有伙伴时，循环在访问字符串外部之前停止。 增加`i`通过两次直接跳转到下一个独立对，避免不必要的检查。 

该解决方案不需要对字符值、重复字母或字母顺序进行特殊处理。 加密仅取决于位置，因此交换索引就足够了。 

## 工作示例

 对于输入单词`ABCDEFG`，处理过程为：

 | 当前指数| 配对处理 | 交换后的状态 |
 | --- | --- | --- |
 | 0 | AB→BA | BCDEFG |
 | 2 | CD → DC | BADC EFG |
 | 4 | EF → FE | BADCFEG |

 最终输出为：```
BADCFEG
```此示例演示了正常情况，其中除最后一个字符之外的每个字符都属于一对。 

对于输入单词`HELLO`，处理过程为：

 | 当前指数| 配对处理 | 交换后的状态 |
 | --- | --- | --- |
 | 0 | HE → EH | 埃洛 |
 | 2 | LL → LL | 埃洛 |

 最终角色`O`没有伙伴，所以输出仍然是：```
EHLLO
```此示例显示奇数长度边界情况并确认保留了最后一个字符。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 在配对交换期间，每个角色最多被访问一次。 |
 | 空间| O(n) | 创建包含字符的列表，以便可以执行交换。 |

 该算法与所有测试用例中的字符总数呈线性缩放。 它避免了重复的字符串重建，即使输入包含许多长单词，也能保持实现的效率。

 ## 边缘情况

 对于单字符输入，算法从索引处开始`0`，但是条件`i + 1 < n`立即为假。 没有发生交换，因此：```
Input:
1
Z

Output:
Z
```循环边界防止无效访问并匹配没有对可交换的规则。 

对于奇数长度的单词，在处理所有完整的对后，有意忽略最后一个字符。 和：```
Input:
1
ABCDE

Output:
BADCE
```算法交换`A`和`B`， 然后`C`和`D`。 人物`E`remains at the end because the loop stops when only one unprocessed character remains.

 对于重复字符：```
Input:
1
AAAA

Output:
AAAA
```该算法仍然执行两次交换，但每次交换交换相同的值。 这证实了该实现不依赖于查找不同的字符，仅依赖于应用位置变换。
