 ## 解决方案
 ## 问题理解

 经过一场精彩的比赛后，您的评分是某个正整数`n`，并且此评级足够高，可以将您置于第 1 级。Codeforces 认为评级至少为`1900`成为第 1 组。在接下来的每场比赛之后，您的评分都会下降`50`。 

任务是确定您在仍处于第 1 级的同时可以参加多少场未来的比赛，相当于需要多少场比赛，直到评分首先严格小于`1900`。 官方给出的例子是`1970 -> 2`,`2035 -> 3`， 和`3549 -> 33`。 

输入包含一个整数`n`，代表比赛成功后立即的评分。 输出是一个整数，即后续比赛的次数，直到评级进入第 2 级。该语句保证了所描述的情况，因此起始评级至少为`1900`。 

这里没有大的组合结构。 时间限制只有一秒，但整个计算应该减少到少数整数运算。 模拟在逻辑上是有效的，但其运行时间随着评级本身而增长。 由于该语句没有给出有用的有限上限`n`，迭代次数取决于的算法`n`没有有意义的最坏情况保证。 常数时间算术公式是自然的目标。 

主要边界情况正是`1900`。 为了```
1900
```正确的输出是```
1
```因为一场比赛结束后，评分会变成`1850`，即第 2 级。如果不小心实施，仅计算以第 1 级评级结束的比赛，可能会返回`0`，但所要求的比赛恰恰是评分越界之后的一场比赛。 

另一个微妙的情况是评级`50`边界以上的点。 为了```
1950
```正确的输出是```
1
```因为第一场比赛将评级更改为`1900`，仍然是第 1 级，但下一场比赛将晋级`1850`。 答案询问在成为第 2 级之前还剩多少场比赛，所以答案是`1`， 不是`2`。 当条件写入不正确时，这是产生相差一错误的常见原因。 

一个更大的例子，例如```
2035
```有输出```
3
```因为连续比赛后的收视率`1985`,`1935`， 和`1885`。 第三场比赛是第一个产生Division 2 评级的比赛。 

## 方法

 直接的方法是模拟比赛。 从当前额定值开始，反复减去`50`直到评级变得小于`1900`，计算执行了多少次减法。 这是正确的，因为模拟完全遵循问题所描述的评级变化，并且循环第一次停止正是玩家第一次进入第 2 级。 

假设起始评级为`n`。 模拟执行

 [
 \左\lfloor\frac{n-1900}{50}\右\rfloor+1
 ]

 迭代。 由于输入没有明确的上限，因此该数字可以任意大。 尽管每次迭代都很便宜，但该算法对起始评分具有线性依赖性，而答案本身可以直接计算。 

关键的观察是，之后`c`比赛，评分为

 [
 n-50c。 
]

 当这个值小于时我们就变成了 Division 2`1900`:

 [
 n-50c < 1900。 
]

 重新排列给出

 [
 50c > n-1900。 
]

 满足这个不等式的最小正整数是

 [
 c=\left\lfloor\frac{n-1900}{50}\right\rfloor+1。 
]

这`+1`处理严格的不平等。 如果`n-1900`已经是的倍数`50`，玩家仍处于评级状态`1900`经过这么多场比赛后，因此需要再进行一场比赛才能进入第 2 级。 

暴力破解之所以有效，是因为每个模拟步骤都对应一场真实的比赛，但当比赛数量很大时，就会失败。 观察到评级每次都会发生固定量的变化，这让我们可以用一次除法和一次加法来替换整个模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n/50) | O(1) | O(1) | 正确，但不必要地依赖`n`|
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取起始评级`n`。 该问题描述了一名刚刚进入一级联赛的球员，因此`n >= 1900`。 
2. 计算`(n - 1900) // 50`。 这告诉我们有多少完全减少`50`起始评级与 1 级边界之间的拟合。 
3.添加`1`到那个值。 需要额外的比赛，因为完全达到`1900`不离开第 1 区。第 2 区仅在下面开始`1900`。 
4. 打印结果计数。 

### 为什么它有效

 之后`c`比赛，评分准确无误`n - 50c`。 当此数量小于时，玩家进入第 2 组`1900`。 最大完整数`50`- 至少保持不变时可能发生的点减少`1900`是`(n - 1900) // 50`。 下一场比赛必然会将评分推低`1900`，所以所需的比赛次数正是`(n - 1900) // 50 + 1`。 该公式还可以正确处理相等边界，因为整数除法会丢弃完整的减少，而最终的结果`+1`表示跨越边界的第一个减少。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
answer = (n - 1900) // 50 + 1
print(answer)
```第一行读取单个评级。 没有测试用例计数，因为问题仅包含一个输入值。 

表达式`(n - 1900) // 50`计算完整的组`50`之间的点`n`和`1900`。 Python 整数除法正是我们所需要的，因为答案取决于在到达边界之前可以发生多少次完全减少。 
决赛`+ 1`是实现的微妙部分。 为了`n = 1900`，商是`0`，所以答案就变成了`1`。 为了`n = 1950`，商是`1`，所以答案也变成`1`。 在后一种情况下，一场比赛的评分来自`1950`到`1900`，并且需要进行以下比赛才能进入第 2 级，这符合答案计算在过渡之前仍然可以完成的比赛的解释。 

Python整数具有任意精度，因此即使输入等级非常大，也不存在溢出问题。

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())
    print((n - 1900) // 50 + 1)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

## 边缘情况

 确切的边界是第一个需要验证的情况。 有输入```
1900
```表达式变为`(1900 - 1900) // 50 + 1`，即`1`。 一场比赛结束后，评分为`1850`，因此玩家已进入第 2 级。没有最终结果的公式`+1`会错误地报告零。 

确切的多重情况稍微微妙一些。 有输入```
1950
```第一场比赛将评级更改为`1900`。 自从`1900`仍然属于第 1 组，该比赛尚未导致过渡。 公式给出`1`，代表在玩家进入第 2 级之前仍可以完成的单场比赛。下一场比赛将产生`1850`。 

对于紧邻边界上方的评级，```
1901
```一场比赛将评级更改为`1851`，已经在下面了`1900`。 公式给出`(1901 - 1900) // 50 + 1 = 1`，正确处理小于的余数`50`。 

最后，考虑一个非常大的评级，例如```
1000000000000000000
```该算法从不模拟评级下降的巨大序列。 它直接评估```
(1000000000000000000 - 1900) // 50 + 1
```并产生```
19999999999999963
```正确性不变，因为推导仅取决于固定的减少`50`和严格边界`1900`，而不是起始评级的大小。
