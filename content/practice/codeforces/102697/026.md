 ## 解决方案
 ## 问题理解

 这是一个介绍性的输入/输出问题。 该程序接收包含比赛规则的一行，其唯一的工作是打印一个固定标题，后跟完全相同的规则行。 标题必须是`Competition Rules:`并且原始输入必须在下一行中保持不变。 官方声明确认，预期的解决方案只是读取该行并将标题和输入打印在单独的行上。 

不存在改变算法选择的数值约束。 如果输入行包含 (L) 个字符，则读取和写入它需要 (O(L)) 时间，因为每个输入字符必须至少处理或发出一次。 如果该行存储为 Python 字符串，则内存使用量为 (O(L))。 由于没有大的数字参数或嵌套结构，因此排序、动态规划、图遍历或强力搜索等算法在这里不起作用。 

主要的边缘情况是空规则行。 例如，```

```包含一个空字符串作为竞争规则。 正确的输出是```
Competition Rules:
```一个粗心的实现调用`strip()`然后假设必须有可见文本可能会意外更改输入或省略第二行。 最安全的方法是读取整行并打印它而不修改其内容。 

另一个容易犯的错误是更改规则内的空格。 例如，与```
Use 2 spaces here.
```正确的输出是```
Competition Rules:
Use 2 spaces here.
```一种将输入拆分为单词并再次连接它们的解决方案可以默默地将多个空格变成一个空格。 没有理由解析规则，因此将整行视为不透明文本可以避免该问题。 

## 方法

 最直接的方法是读取一个输入行并打印所需的标题，然后打印该行。 对于这个问题，没有有意义的组合暴力算法，因为输出完全由输入决定。 

如果我们想将其与故意低效的实现进行对比，假设我们使用重复串联将输入一次一个字符复制到不断增长的 Python 字符串中。 对于长度为 (L) 的行，可以在每次追加后复制累积的字符串，大致给出

 [
 1 + 2 + 3 + \dots + L = \frac{L(L+1)}{2}
 ]

 最坏情况下的字符复制操作。 即 (O(L^2))，即使该任务只需要复制 (L) 个字符。 

观察到输入已经完全包含我们需要打印的文本，从而消除了所有转换工作。 我们可以将整行保留为一个字符串并直接输出。 因此，最佳解决方案仅执行线性工作，这也是自然下限，因为输出本身包含 (L) 个输入字符。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 重复字符串构造 | O(L²) | O(L) | 不必要的缓慢 |
 | 直接读取并打印| O(L) | O(L) | 已接受 |

 ## 算法演练

 1. 阅读包含竞赛规则的单行内容。 我们将该行保留为文本而不是拆分它，因为每个字符（包括空格）都属于所需的输出。 
2.打印固定字符串`Competition Rules:`。 这与输入无关，并且始终占据第一条输出线。 
3. 完全按照读取的内容打印输入行。 换行符已被消耗`readline()`在打印之前被删除，以便`print()`不会创建额外的空行。 

### 为什么它有效

 输入仅由一个规则行组成，所需的输出由两行组成：固定标题和相同的规则行。 该算法打印固定的第一行，然后精确打印存储的输入文本作为第二行。 由于没有对规则应用任何转换，因此应保留的每个字符都保持不变，因此生成的输出与所需的格式匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    rules = input().rstrip('\n')
    print("Competition Rules:")
    print(rules)

if __name__ == "__main__":
    solve()
```致电给`input()`读取单个规则行。 使用`rstrip('\n')`仅删除输入操作添加的行结束字符。 这比使用更精确`strip()`， 因为`strip()`还将删除规则开头或结尾的有意义的空格。 

第一个`print()`产生问题所需的固定标题。 第二个`print()`在单独的行上生成规则。 

没有整数转换、索引、排序或其他算法处理。 Python 整数和溢出是无关的，因为输入是纯文本。 

## 工作示例

 官方示例包含以下规则行：```
This is a competition rule
```执行过程可总结如下。 

| 步骤|`rules`| 输出|
 | --- | --- | --- |
 | 1 |`This is a competition rule`| |
 | 2 |`This is a competition rule`|`Competition Rules:`|
 | 3 |`This is a competition rule`|`Competition Rules:`其次是`This is a competition rule`|

 跟踪表明输入未被解释或修改。 它只是放置在所需标题之后。 

具有重复空格的第二个示例很有用，因为它捕获了对输入进行标记的解决方案。 

输入：```
Rules  contain   extra spaces
```执行过程是：

 | 步骤|`rules`| 输出|
 | --- | --- | --- |
 | 1 |`Rules  contain   extra spaces`| |
 | 2 |`Rules  contain   extra spaces`|`Competition Rules:`|
 | 3 |`Rules  contain   extra spaces`|`Competition Rules:`其次是`Rules  contain   extra spaces`|

 多个空格保持不变。 这正是为什么规则应该被视为一个字符串而不是从单个单词重建的原因。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(L) | 读取和打印规则处理 (L) 个字符 |
 | 空间| O(L) | 完整的规则行存储在内存中 |

 这里（L）是输入线的长度。 该解决方案实际上是最优的，因为生成输出已经需要写入规则中的所有 (L) 字符。 该问题不存在可能使该方法不适用的更大结构性约束。 

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    rules = input().rstrip('\n')
    print("Competition Rules:")
    print(rules)

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    input = sys.stdin.readline

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
assert run("This is a competition rule\n") == (
    "Competition Rules:\n"
    "This is a competition rule\n"
), "sample 1"

# Empty rules line
assert run("\n") == (
    "Competition Rules:\n"
    "\n"
), "empty rules"

# Repeated spaces
assert run("Rules  contain   extra spaces\n") == (
    "Competition Rules:\n"
    "Rules  contain   extra spaces\n"
), "preserve spaces"

# Leading and trailing spaces
assert run("  padded rules  \n") == (
    "Competition Rules:\n"
    "  padded rules  \n"
), "preserve boundary spaces"

# A longer single line
long_rules = "A" * 100000
assert run(long_rules + "\n") == (
    "Competition Rules:\n" + long_rules + "\n"
), "large input line"

 ## 边缘情况

 空规则行由以下方式处理`rstrip('\n')`，这会产生空字符串。 然后该算法打印标题并调用`print("")`，生成所需的空白第二行。 用于输入```

```输出是```
Competition Rules:
```包含重复内部空格的行被保留，因为程序从不调用`split()`。 用于输入```
Rules  contain   extra spaces
```所存储的价值仍然存在`Rules  contain   extra spaces`，并打印相同的序列。 基于文字的解决方案可能会错误地折叠这些空间。 

前导或尾随空格也被保留，因为代码仅删除换行符。 和```
  padded rules
```输出包含与提供的完全相同的两个前导空格和两个尾随空格。 呼唤`strip()`相反会默默地删除它们。 

最后，很长的输入行不会改变算法。 如果该行有 (L) 个字符，则程序仍执行 (O(L)) 工作并存储 (O(L)) 个字符，这是输出复制问题的适当成本。
