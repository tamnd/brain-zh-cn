 ## 解决方案
 # 问题理解

 该问题描述了一个地铁网络，其中每条线路都以它所访问的车站的有序列表的形式给出。 第一站是机场，目标是酒店。 乘客可以沿着包含当前车站的线路乘坐。 从一条地铁线换乘另一条地铁线算作乘坐另一条地铁线，而继续乘坐同一条地铁线则不会增加计数。 任务是找到从机场到酒店所需的最少数量的不同地铁线路。 

查看输入的有用方法不是通过轨道连接的车站图表，因为成本不是经过的车站数量。 一条线路的长途乘车费用与该线路的短途乘车费用相同。 唯一改变答案的事件是进入新的地铁线路。 

不同车站的数量足够少，因此在地铁网络上进行图搜索是可行的。 如果有数十万个车站或线路，我们需要更仔细的预处理，但这里输入中车站出现的总数是有限的，因此在线路和换乘站之间建立明确的关系是可行的。 对所有可能的车站路径进行二次搜索仍然是浪费，因为乘客不关心线路内的中间车站。 

棘手的情况是多条线路共用一个车站或起点和终点在同一条线路上的情况。 例如：```
3
Airport A Hotel
A B C
C Hotel
```正确答案是`1`，因为第一条线路已经连接了两个所需的车站。 一个粗心的解决方案是计算访问过的车站而不是线路变化，会产生更大的答案。 

另一种情况是需要立即转账：```
2
Airport X
X Hotel
```正确答案是`2`。 乘客必须先乘坐机场线，然后在X站换乘酒店线。 

第三种情况是通过同一车站多次换乘：```
3
Airport A
A B
B Hotel
```答案是`3`。 将车站视为主要图表并忘记每次线路变更都会产生成本可能会低估答案。 

## 方法

 一种简单的方法是搜索可能的车站路径。 从机场出发，我们可以反复尝试当前地铁线路可到达的每个车站，并记录已经使用了多少条线路。 这是正确的，因为每一个可能的旅程都被考虑了，但它探索了许多等效的路径。 乘坐同一条线路从一个车站到另一个车站会产生许多不必要的状态。 

关键的观察结果是，当乘客停留在线路上时，线路内的确切车站并不重要。 有意义的状态是当前的地铁线路。 如果我们知道当前正在使用 X 线，我们可以立即到达 X 线所服务的每个车站，而无需支付另一条线路的费用。 从 X 线上的任何车站，我们可以转乘经过该车站的所有其他线路，并支付额外的费用。 

这将问题转化为地铁线路上的最短路径问题。 每个节点代表一条地铁线路。 如果两条线路共享至少一个车站，则它们之间存在边。 边缘成本为 1，因为从一条线移动到另一条线会在旅程中增加一条线。 起始节点是包含机场的所有线路，初始成本为 1。 然后，广度优先搜索会找到到达包含酒店的任何线路所需的最少线路数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解车站路径 | 选择数量呈指数级增长 | O(状态数) | 太慢了 |
 | 地铁线路上的 BFS | O(全站仪出现次数 + 传输次数) | O(线路数 + 车站数) | 已接受 |

 ## 算法演练

 1. 读取每条地铁线路并存储属于该线路的车站。 同时，构建从每个车站到访问该车站的地铁线路列表的映射。 这种反向映射是重要的结构，因为换乘发生在车站。 
2. 查找包含机场的所有地铁线路。 将这些行放入距离为 1 的 BFS 队列中。 从距离 1 开始表示使用任何地铁线路都已算作乘坐一条线路。 
3. 从队列中弹出一条地铁线路。 对于该线路上的每个车站，检查经过该车站的所有其他地铁线路。 如果这样的线路还没有被访问过，则为其分配一个更大的距离并将其添加到队列中。 
4.每当访问的线路包含酒店站时，存储的距离就是所需的最少地铁线路数。 

为什么它有效：

 BFS 按使用的地铁线路数量的递增顺序探索各州。 在线路内移动不需要额外费用，因此线路上的所有车站都会一起处理。 每个可能的转移都由两条线之间的边缘表示。 由于 BFS 在未加权图中找到最短路径，因此当我们第一次到达酒店线路时，我们已经找到了尽可能少的线路数。 

## Python 解决方案```python
import sys
from collections import deque, defaultdict

input = sys.stdin.readline

def solve():
    n = int(input())
    
    lines = []
    station_to_lines = defaultdict(list)
    
    for i in range(n):
        stations = input().split()
        lines.append(stations)
        for s in stations:
            station_to_lines[s].append(i)

    start = "Airport"
    target = "Hotel"

    dist = [-1] * n
    q = deque()

    for line in station_to_lines[start]:
        dist[line] = 1
        q.append(line)

    answer = -1

    while q:
        line = q.popleft()

        if target in lines[line]:
            answer = dist[line]
            break

        for station in lines[line]:
            for nxt in station_to_lines[station]:
                if dist[nxt] == -1:
                    dist[nxt] = dist[line] + 1
                    q.append(nxt)

    print(answer)

if __name__ == "__main__":
    solve()
```名单`station_to_lines`是地铁系统的反向指数。 如果没有它，每次传输都需要扫描每一行，这会不必要地增加运行时间。 

BFS队列存储的是地铁线路而不是车站。 这避免了将沿单线的移动计算为额外成本。 距离数组以线路号为索引，其值正是到达该线路所用的地铁线路数。 

初始化是错误的常见来源。 第一条地铁线已经为答案贡献了一个，因此起始距离必须是`1`， 不是`0`。 

当队伍从队列中移除时，酒店的检查就完成了。 由于 BFS 按距离递增的顺序删除状态，因此找到的第一条这样的线是最佳的。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(S + T) | S为所有线路的出站总数，T为相连线路之间的换乘检查次数|
 | 空间| O(S)| 存储的线路列表和车站到线路的映射包含每个车站的出现|

 输入大小足够小，显式存储每个站点的出现是安全的。 BFS 访问每条地铁线路一次，并通过车站映射检查每条换乘关系。

import sys
import io
from collections import deque, defaultdict

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)

    n = int(input())
    lines = []
    station_to_lines = defaultdict(list)

    for i in range(n):
        stations = input().split()
        lines.append(stations)
        for s in stations:
            station_to_lines[s].append(i)

    dist = [-1] * n
    q = deque()

    for x in station_to_lines["Airport"]:
        dist[x] = 1
        q.append(x)

    ans = -1
    while q:
        x = q.popleft()
        if "Hotel" in lines[x]:
            ans = dist[x]
            break
        for s in lines[x]:
            for y in station_to_lines[s]:
                if dist[y] == -1:
                    dist[y] = dist[x] + 1
                    q.append(y)

    sys.stdin = old
    return str(ans)

 ## 边缘情况

 当机场和酒店在同一条地铁线上时，BFS 从距离为 1 的那条线路开始，并立即返回 1。 该算法从不强制进行不必要的传输。 

为了：```
1
Airport Hotel
```队列最初包含唯一有距离的行`1`。 由于该行包含 Hotel，所以答案是`1`。 

当换乘站属于多条线路时，反向映射可能包含许多候选。 该算法检查每个候选者一次，因为每条线仅在第一次发现时才接收距离。 

为了：```
3
Airport X
X Y
X Hotel
```第一条线路通过 X 站到达其他两条线路。酒店线路指定距离`2`，这是可能的最小值。 

如果多条线路共享车站但不通往酒店，则仍仅处理一次。 这可以防止重复探索同一个传输站，并使 BFS 保持在所需的复杂性范围内。
