 ## 解决方案
 ## 问题理解

 任务是评估包含通过加法和减法连接的整数的单个算术方程。 方程以等号结尾，所需的输出保持原始方程不变，同时附加其数值结果。 

例如，输入`1 + 5 + 7 - 2 =`表示计算(1+5+7-2)，其值为(11)。 所需的输出是`1 + 5 + 7 - 2 = 11`。 问题陈述没有给出方程大小的单独数字界限，但时间限制为一秒，并且表达式是普通输入字符串。 这使得线性扫描成为自然的目标。 如果表达式有 (L) 个字符，则 (O(L)) 解决方案对每个字符执行恒定量的工作，而重复重新扫描表达式可能会增长到 (O(L^2))。 

主要的边缘情况来自于减法不可交换以及等号是输入格式的一部分这一事实。 为了`8 - 3 - 2 =`，正确的输出是`8 - 3 - 2 = 3`。 将所有数字视为正数的粗心实现会产生 (13)，而将减法解释为单个运算的实现可能会产生错误的分组。 

为了`5 - 5 + 5 - 5 =`，正确的输出是`5 - 5 + 5 - 5 = 0`。 这会捕获意外添加每个已解析数字并仅在之后检查运算符的实现。 

对于最小的有用方程，`7 =`，正确的输出是`7 = 7`。 没有运算符来处理，因此第一个数字必须直接成为结果。 

## 方法

 一种简单的方法是重复搜索剩余的表达式以查找下一个数字及其后面的运算符。 这是正确的，因为表达式仅包含加法和减法，因此从左到右计算项会准确给出算术结果。 这种实现的问题是不必要的重新扫描。 如果每次搜索都从未处理部分的开头重新开始，则包含 (L) 个字符的表达式可能会导致大约 (L+(L-1)+\cdots+1=O(L^2)) 个字符检查。 对于足够长的输入，二次行为是可以避免的工作。 

关键的观察结果是加法和减法没有优先级差异。 一旦读取了一个数字及其符号，它对最终答案的贡献就完全确定了。 我们永远不需要重温早期的角色。 单次从左到右扫描可以累加当前数字，每当遇到加号或减号时，可以立即将完成的数字与答案相加或相减。 

等号不参与计算。 它只是标记算术表达式的结束。 当我们到达它时，我们可以停止处理并保留原始输入行以获取所需的输出。 

因此，两种方法之间的区别并不是更复杂的数学技术。 它认识到表达式是独立签名术语的流，因此每个字符只需要检查一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(L²) | O(L) | 对于大型表达式来说太慢 |
 | 最佳 | O(L) | O(1) | O(1) | 已接受 |

 这里（L）表示输入方程的长度。 

## 算法演练

 1. 将完整的方程作为字符串读取，并准确保存以用于最终输出。 原始格式是问题要求我们打印的一部分。 
2. 从左到右扫描方程，同时保留累积的答案、当前数字以及将应用于该数字的符号。 从正号开始自然可以处理第一个数字。 
3. 当遇到数字时，用该数字扩展当前数字。 例如，阅读`42`将当前数字更改为`4`到`42`。 
4. 什么时候`+`或者`-`遇到符号时，将先前存储的符号应用于已完成的当前数字，然后将当前数字重置为零并记住新遇到的符号。 在更改符号之前处理前一个数字可以避免将其与错误的运算符相关联。 
5. 什么时候`=`遇到时，使用其存储的符号应用最终数字并停止。 此时方程已完成。 
6. 打印未修改的原始方程，后跟一个空格和计算出的答案。 这将计算表达式与格式化所需的输出分开。 

### 为什么它有效

 在扫描期间的每个点，累积的答案等于当前数字之前出现的每个完整项的值。 当前数字恰好包含下一项的数字，并且存储的符号恰好是紧邻该项之前的运算符。 当到达运算符或等号时，应用该符号将精确地添加下一项对累积答案的贡献。 由于每个术语都只处理一次，并且最终术语在以下时间处理：`=`达到时，最后的累加值正是整个方程的值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    equation = input().rstrip("\n")

    answer = 0
    number = 0
    sign = 1

    for ch in equation:
        if ch.isdigit():
            number = number * 10 + ord(ch) - ord('0')
        elif ch == '+' or ch == '-':
            answer += sign * number
            number = 0
            sign = 1 if ch == '+' else -1
        elif ch == '=':
            break

    answer += sign * number

    print(equation + " " + str(answer))

if __name__ == "__main__":
    solve()
```这`equation`变量存储原始行，以便输出可以重现它而无需重建表达式。 使用`rstrip("\n")`仅删除行结尾，而不是从方程中删除任意空格。 

扫描器将每个数字视为当前整数的一部分。 该表达式可能包含多位值，因此替换`number`使用当前数字将不正确。 更新内容`number = number * 10 + digit`以通常的方式构造十进制整数。 

当找到运算符时，代码首先使用旧符号添加当前数字。 只有之后它才会改变标志。 此顺序对于以下表达式至关重要`10 - 3 + 4 =`。 

等号终止求值，因为它后面的所有内容都将在算术表达式之外。 决赛`answer += sign * number`是必要的，因为最后一个数字后面没有运算符来触发处理。 

对于普通整数输入大小，Python 整数不会溢出，因此不需要特殊的溢出处理。

import io

def solve():
    equation = input().rstrip("\n")

    answer = 0
    number = 0
    sign = 1

    for ch in equation:

            number = number * 10 + ord(ch) - ord('0')

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
assert run("1 + 5 + 7 - 2 =\n") == "1 + 5 + 7 - 2 = 11\n", "sample 1"

# Minimum-size equation

# All values cancel

# Multi-digit values and repeated subtraction

 ## 边缘情况

 对于单数情况`7 =`，扫描仪读取`7`进入`number`，达到`=`，然后使用初始正号添加最后一项。 结果是`7`，所以输出是`7 = 7`。 该算法不需要任何操作员即可工作。 

为了`8 - 3 - 2 =`，第一个`-`原因`8`被添加并将符号更改为负数。 第二个`-`添加`-3`并在下一个术语中保留负号。 决赛`2`因此被减去，产生`3`。 输出是`8 - 3 - 2 = 3`。 

为了`5 - 5 + 5 - 5 =`，答案演变为 (5)、(0)、(5)，最后是 (0)。 每个运算符仅适用于紧随其后的数字，而累加器包含所有已完成的项。 

对于包含 100000 个术语的大型表达式，例如`1 + 1 + 1 + ... + 1 =`，扫描仪仍然访问每个字符一次。 答案就变成了`100000`，并且没有嵌套循环或重复的子字符串搜索可以将工作变成二次时间。
