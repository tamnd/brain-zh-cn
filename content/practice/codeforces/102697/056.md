 ## 解决方案
 ## 问题理解

 秒表仅存储经过的总秒数。 我们需要使用年、日、小时、分钟和秒将该单个数字转换为人类可读的持续时间。 

对于这个问题，一年被视为365天。 一天有24小时，一小时有60分钟，一分钟有60秒。 输出应仅包含值非零的单位，并具有正确的单数或复数措辞以及自然的英语标点符号。 如果没有经过时间，答案很简单`now`。 官方说法给出了1秒的时间限制和256MB的内存限制。 

输入中只有一个整数，表示经过的秒数。 不涉及单独的测试计数或数组，因此整个计算可以通过恒定数量的算术运算来完成。 该语句没有为该整数提供明确的上限，因此我们不应该构建一个运行时间取决于其大小的算法。 Python 整数还避免了普通竞赛输入的溢出问题，但解决方案本身只需要除法和余数运算。 

主要的边缘情况是由格式而不是算术引起的。 例如，输入`0`必须产生`now`， 不是`0 seconds`，因为省略了零值持续时间，并且有一个特殊的表示形式来表示没有经过的时间。 

输入`60`必须产生`1 minute`， 不是`1 minutes`而不是`0 hours and 1 minute`。 粗心的实现可能总是打印每个单元，或者可能会附加`s`机械地不检查该值是否为一。 

输入`86400`必须产生`1 day`。 小时、分钟和秒部分均为零，因此它们都不应该出现在结果中。 

输入`31536000`必须产生`1 year`。 这正好是 365 天，因此整个持续时间都属于年份部分。 

最后输入`61`必须产生`1 minute and 1 second`。 对于两个非零分量，分隔符是`and`没有逗号。 对于更大的例子，例如`3661`，输出是`1 hour, 1 minute and 1 second`，因此最后两个组件的连接方式与前面的组件不同。 

## 方法

 最直接的暴力解决方案会反复从剩余持续时间中减去一秒并增加计数器。 这是正确的，因为每次迭代正好代表经过的一秒，所以之后`N`迭代计数器描述原始的`N`秒。 问题是输入包含`N`秒需要`N`迭代。 因此，最坏情况的操作计数为 θ(N)，其中`N`是输入值。 由于该任务有 1 秒的限制，因此没有理由假设`N`很小，运行时间随着秒数增加的解决方案是不必要的危险。 

时间单位的结构为我们提供了一条更简单的路线。 每个较大的单元都由固定数量的较小单元组成。 一年恰好包含`365 * 24 * 60 * 60`秒，一天包含`24 * 60 * 60`秒，一小时包含`60 * 60`秒，一分钟包含`60`秒。 

这意味着整数除法立即告诉我们剩余持续时间中有多少个完整的单位，而余数则准确地给出了下一个较小单位剩余的内容。 我们可以对五个单元中的每一个执行一次分解，因此无论输入有多大，算术都需要恒定的时间。 

计算出五个值后，格式化成为唯一剩下的任务。 我们按照自然顺序收集非零成分，将每个成分转换为其单数或复数形式，然后使用所需的英语规则连接生成的短语。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N) | O(1) | O(1) | 对于大N来说太慢|
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取经过的总秒数。 如果为零，则打印`now`立即，因为没有要格式化的非零时间分量。 
2. 使用整数除以计算完整年数`365 * 24 * 60 * 60`。 将剩余的秒数替换为余数。 这会删除每个完整的年份，同时保留仍需要表示的确切数量。 
3. 使用除法从剩余秒数计算完整天数`24 * 60 * 60`，然后保留余数。 对小时应用相同的过程`60 * 60`，并使用分钟`60`。 
4. 除去完整分钟后剩下的秒数已经是最后的秒数组成部分。 不需要进一步划分。 
5. 对于每个非零分量，创建一个短语，例如`1 hour`或者`7 hours`。 当值为`1`; 所有其他正值都使用复数形式。 
6. 根据编号将短语连接起来。 一句话，直接打印出来。 用两个短语，把`and`他们之间。 对于三个或更多短语，用逗号分隔前面的短语并放置`and`最后两者之间。 

### 为什么它有效

 每次除法和求余运算后，剩余的值正是原始持续时间中无法用已处理的单元表示的部分。 由于每个单位都是下一个较小单位的精确倍数，因此不会丢弃小数部分。 最后，五个计算组件准确地重建了原始秒数，因此错误答案的唯一可能来源是格式。 最终结构显式地删除零分量并应用所需的单数、复数、逗号和`and`规则，因此打印的句子准确地代表了该分解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    total = int(input())

    if total == 0:
        print("now")
        return

    units = [
        ("year", 365 * 24 * 60 * 60),
        ("day", 24 * 60 * 60),
        ("hour", 60 * 60),
        ("minute", 60),
        ("second", 1),
    ]

    parts = []

    for name, size in units:
        count, total = divmod(total, size)

        if count == 0:
            continue

        word = name if count == 1 else name + "s"
        parts.append(f"{count} {word}")

    if len(parts) == 1:
        print(parts[0])
    elif len(parts) == 2:
        print(parts[0] + " and " + parts[1])
    else:
        print(", ".join(parts[:-1]) + " and " + parts[-1])

if __name__ == "__main__":
    solve()
```这`units`数组存储每个单元及其大小（以秒为单位），按从最大到最小的顺序排列。 这个顺序就是重复的原因`divmod`调用作为一个干净的分解工作。`divmod(total, size)`在一次操作中返回完整单元的数量和余数。 将余数分配回`total`意味着下一次迭代仅适用于尚未考虑的部分。 

在格式化之前会跳过零组件，这样可以处理诸如恰好一天之类的情况，而不需要几小时、几分钟或几秒的特殊情况。 

单一检查使用`count == 1`。 其他所有正值都是复数，因此诸如`0`永远不会到达此代码，因为已经跳过了零个组件。 

最终的连接逻辑故意与数值分解分开。 这避免了尝试处理逗号和`and`计算时间值时，这是格式错误的常见来源。 

Python 中不存在溢出问题，因为它的整数具有任意精度。 该算法还只执行固定数量的算术运算，因此其运行时间不依赖于经过的秒数。

## 边缘情况

 对于零持续时间的情况，确切的输入是`0`。 算法达到初始值`if total == 0`检查并打印`now`立即地。 如果没有这个分支，组件列表将为空，粗心的实现可能会打印空行或`0 seconds`。 

对于精确的一分钟，输入是`60`。 年、日和小时均为零。 分钟计算得出`1`与余数`0`，所以唯一存储的短语是`1 minute`。 这既捕获了零分量的省略，又捕获了单数形式。 

对于确切的年份，输入是`31536000`， 因为`365 * 24 * 60 * 60 = 31536000`。 年份计算得出`1`并留下零秒。 结果正是`1 year`。 这里使用 365 天很重要，因为这是该问题分解所使用的固定年份长度。 

对于只有两个非零分量的持续时间，输入`61`给出零年、零天和零小时，然后`1 minute`和`1 second`。 最终列表的长度为 2，因此输出为`1 minute and 1 second`。 总是使用逗号的格式化程序会错误地生成`1 minute, and 1 second`。 

在所有五个组件都存在的持续时间内，样本输入`98753213`产生`3 years`,`47 days`,`23 hours`,`26 minutes`， 和`53 seconds`。 重复的余数运算保留每个单元后未处理的部分，最终格式化生成所需的逗号分隔序列`and`仅在最后一个组件之前。
