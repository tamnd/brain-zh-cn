 ## 解决方案
 ## 问题理解

 我们给出一个包含整数区间`x`到`y`。 在该区间内的所有数字中，我们需要找到最大的 2 的幂。 如果区间不包含 2 的幂，我们打印`-1`。 答案必须符合有符号 32 位整数。 

两者的相关权力是`1, 2, 4, 8, 16, ...`。 由于答案适合有符号 32 位整数，因此最大可能的答案是`2^30 = 1073741824`。 下一个力量，`2^31`, 超出有符号 32 位范围。 这让我们只考虑了 31 项候选人权力。 

时间限制为 1 秒，内存限制为 256 MB。 该语句不会强加大型数组或图形结构，因为输入仅包含两个整数。 当间隔很大时，对间隔中每个整数的线性扫描仍然可能需要超过 20 亿次迭代，因此有用的观察结果是 2 的幂非常稀疏。 仅检查幂本身需要对数时间。 

有几种边界情况可能会导致粗心的实施失败。 如果区间本身包含 2 的幂，则端点包含在内。 例如，使用输入`8 8`，正确的输出是`8`。 仅在端点之间严格搜索的实现将错误地打印`-1`。 

另一种情况是，上端点不是 2 的幂，但低于它的最大幂在区间内。 用于输入`86 375`，区间附近的幂为`64`,`128`， 和`256`，所以答案是`256`。 选择第一个至少为`x`会错的，因为`128`有效但不是最大值。 

最后，一个区间根本不能包含二的幂。 用于输入`35 55`，周围的势力是`32`和`64`，都在区间之外，所以答案是`-1`。 一个粗心的实现，简单地计算不超过的最大功率`y`会得到`32`并且忘记验证它是否至少也是`x`。 

## 方法

 直接的方法是检查每个整数`x`通过`y`，测试是否是2的幂，记住最大的成功值。 该方法是正确的，因为每个可能的答案都被明确检查。 当正整数的二进制表示包含一组位时，它就是 2 的幂，因此可以通过位运算来完成测试，例如`v & (v - 1) == 0`。 

问题是检查的整数的数量。 在最坏的情况下，间隔如`[1, 2147483647]`包含`2147483647`候选人。 即使每个候选者只需要几次恒定时间操作，数十亿次迭代也远远超出了 1 秒的限制。 

蛮力之所以有效，是因为它会检查所有可能的答案，但当间隔很宽时就会失败。 解锁更快解决方案的观察结果是我们根本不需要检查普通整数。 唯一可能的答案是 2 的幂，并且连续幂的差异在于乘以 2。 开始于`1`，我们可以通过重复加倍来生成每个相关的候选者。 

有符号的 32 位范围内大约只有 31 个 2 的幂。 我们可以将它们全部生成并保留区间中最大的一个，或者找到两个不超过的最大幂`y`并检查是否至少是`x`。 第二种公式尤其简单。 一旦我们达到最大的力量`p`满意的`p <= y`，每个较大的幂都会自动大于`y`， 所以`p`是唯一可能成为答案的候选人。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(y - x + 1) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(log y) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`x`和`y`。 该区间是包含在内的，因此两个端点都可以作为答案。 
2. 开始于`p = 1`，2 的最小正幂。 随后的每一个功率都可以通过将前一个功率加倍来获得。 
3.翻倍时`p`顶多还是会保留`y`， 代替`p`和`2 * p`。 当循环停止时，`p`是两个满足的最大幂`p <= y`。 
4. 检查是否`p >= x`。 如果是的话，那么`p`位于里面`[x, y]`，并且它是该区间内最大可能的二的幂，因此打印`p`。 
5.如果`p < x`， 打印`-1`。 自从`p`已经是不超过的最大的二的幂`y`，每一个其他的二的幂最多是`p`或大于`y`。 因此，该区间内不能存在任何功率。 

不变量是每次迭代后，`p`是 2 的幂，并且是不超过其当前上限的最大生成功率。 终止时，`p`最多是两个的最大幂`y`。 如果它也是至少`x`，这正是最大的有效答案。 如果是下面的`x`，不能有任何有效的幂，因为所有后来的幂都超过`y`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())

    p = 1

    while p * 2 <= y:
        p *= 2

    if x <= p <= y:
        print(p)
    else:
        print(-1)

if __name__ == "__main__":
    solve()
```第一行`solve`读取两个端点。 不需要数组或辅助数据结构，因为答案仅取决于当前的 2 的幂。 

变量`p`开始于`1`。 循环将其加倍，而下一个功率仍然低于或恰好在`y`。 使用`p * 2 <= y`而不是首先加倍可以避免在上限之上创建不必要的候选者。 

循环结束后，`p`保证满足`p <= y`什么时候`y >= 1`。 最终条件检查区间的另一边，`p >= x`。 将完整条件写为`x <= p <= y`也使包容性边界变得明确。 

Python 整数不会溢出，因此即使是最终可能加倍后的临时值也是安全的。 在具有固定宽度整数的语言中，实现应避免转移到有符号溢出范围。 这里保证答案本身适合有符号的 32 位整数。 

如果`y < 1`，循环不执行加倍并且`p`遗迹`1`。 决赛`p <= y`检查失败，因此算法正确报告`-1`。 这也处理仅包含非正整数的区间。 

## 工作示例

 对于第一个样本，输入是`6 18`。 

| 步骤|`p`之前|`2 * p <= y`|`p`之后|
 | ---| ---| ---| ---|
 | 开始| 1 |`2 <= 18`| 1 |
 | 1 | 1 | 真实 | 2 |
 | 2 | 2 | 真实 | 4 |
 | 3 | 4 | 真实 | 8 |
 | 4 | 8 | 真实 | 16 | 16
 | 5 | 16 | 16`32 <= 18`假 | 16 | 16

 最终值为`16`。 它满足`6 <= 16 <= 18`，所以输出是`16`。 该迹线显示了为什么我们只需要上端点以下的最大功率。 每个更大的功率开始于`32`，已经在区间之外了。 

对于第二个样本，输入是`35 55`。 

| 步骤|`p`之前|`2 * p <= y`|`p`之后|
 | ---| ---| ---| ---|
 | 开始| 1 |`2 <= 55`| 1 |
 | 1 | 1 | 真实 | 2 |
 | 2 | 2 | 真实 | 4 |
 | 3 | 4 | 真实 | 8 |
 | 4 | 8 | 真实 | 16 | 16
 | 5 | 16 | 16 真实 | 32 | 32
 | 6 | 32 | 32`64 <= 55`假 | 32 | 32

 最终值为`32`，但它小于`x = 35`。 下一个功率是`64`，这超过了`y = 55`，所以没有有效的二的幂并且算法打印`-1`。 该跟踪说明了为什么最终的下限检查是必要的。 

对于第三个样本，`86 375`，产生的功率最终达到`256`。 再次加倍给出`512`，即上面的`375`， 所以`256`是不超过上端点的最大功率。 自从`256 >= 86`，这就是答案。

def run(inp: str) -> str:

    old_stdout = sys.stdout

 ## 边缘情况

 当区间恰好包含一次幂时，算法通过包含比较来处理。 对于输入`8 8`,`p`最终变成`8`，以及条件`8 <= 8 <= 8`成功，所以输出是`8`。 使用严格不等式的实现在这里会失败。 

当区间内不存在二的幂时，最大幂不超过`y`低于`x`。 为了`35 55`，循环停止于`32`。 自从`32 < 35`，算法打印`-1`。 下一个力量，`64`，不能考虑，因为它已经大于`y`。 

当间隔极大时，算法不依赖于其宽度。 为了`1 2147483647`，它产生的功率最多可达`1073741824`。 下一个功率是`2147483648`，超过了上端点，所以答案是`1073741824`。 扫描每个整数将需要超过 20 亿次迭代，而此解决方案只需要几十次。 

当端点都是相同的非功率值时，例如`2147483647 2147483647`，该算法在没有特殊情况的情况下仍然有效。 不超过该值的最大功率为`1073741824`，它低于下端点，因为两个端点相等`2147483647`。 最终检查结果会产生`-1`。 

中心思想非常简单，可以重复使用：当所需值形成具有可预测的下一个元素的稀疏序列时，搜索该序列而不是扫描数字区间中的每个值。 这里的顺序是`1, 2, 4, 8, ...`，因此重复加倍会将潜在的数十亿次迭代搜索减少到对数时间。
