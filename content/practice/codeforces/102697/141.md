 ## 解决方案
 ## 问题理解

 当字母表中的每个字符后面紧跟着下一个字符时，该字符串被称为“majestic”。 字母表是圆形的，所以之后`z`来了`a`。 例如，`cdefghij`是宏伟的，因为每个转变都前进一个字母，而`acd`不是因为`a`接下来是`c`而不是`b`。 相似地，`xyzab`是有效的，因为从`z`到`a`是允许的。 

输入由一个字符串组成`s`。 输出应该是`YES`如果每个相邻对都遵循此规则，并且`NO`一旦至少一对相邻的不存在。 

官方说法给出了1秒的时间限制和256MB的内存。 它没有公开字符串的单独最大长度，因此安全的设计是使运行时间与字符数呈线性关系。 单遍对每个相邻对执行一次恒定时间检查，这是最佳的，因为无效的字符转换可能发生在输入中的任何位置，并且我们可能需要检查整个字符串。 随着字符串的增长，二次或指数方法会变得不必要的昂贵。 

有一些小情况可能会导致实施悄无声息地失败。 单字符字符串，例如`a`根本没有相邻对，所以它是宏伟的，正确的输出是`YES`。 假设总是有一对要检查的代码可能会错误地拒绝它。 

概括来自`z`到`a`是另一个重要案例。 用于输入```
yzab
```正确的输出是`YES`。 仅要求下一个字符的 ASCII 值恰好大一个的检查将被拒绝`za`，即使该问题明确将字母表视为循环。 

重复的字符也必须被拒绝。 用于输入```
hellllo
```正确的输出是`NO`。 特别是重复的`l`字符不会在字母表中前进，因此仅检查字符是否按字母顺序排列是不够的。 

## 方法

 完全暴力的解释将生成相同长度的每个可能的字符串，并测试每个候选者是否是伟大的，当找到输入本身时停止。 对于一个长度的字符串`n`， 有`26^n`可能的小写字符串，并检查一个候选成本`n - 1`相邻比较。 在最坏的情况下，这大约给出`26^n(n - 1)`字符检查。 该方法是正确的，因为它明确地考虑了每个可能的字符串，但其指数增长使其即使对于适度的值也毫无用处`n`。 

暴力方法之所以有效，是因为它最终会准确地检查我们关心的属性，但它几乎所有的工作都在考虑与输入无关的字符串。 关键的观察是我们根本不需要寻找一个宏伟的字符串。 输入已经是固定的，并且雄伟是由每个相邻对独立确定的。 

对于一个角色`c`，唯一有效的下一个字符是`(c + 1) mod 26`当字符由从零开始的字母位置表示时。 因此我们可以扫描一次输入。 在位置`i`，我们比较`s[i + 1]`与所需的后继者`s[i]`。 不匹配立即证明整个字符串并不宏伟。 如果扫描到达末尾且没有不匹配，则每个相邻的转换都是有效的并且字符串是宏伟的。 

这将工作从字符串长度的指数变为线性，同时使用恒定的额外空间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(26^n·n) | O(26^n·n) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取单个输入字符串并删除尾随换行符。 
2. 遍历每一个相邻的对`s[i]`,`s[i + 1]`。 正好有`n - 1`这样的对对于长度的字符串`n`，因此不会跳过任何转换。 
3. 将当前字符转换为从零开始的字母位置。 它所需的后继者是一个位置之后，从`z`回到`a`。 
4. 将所需的后继者与`s[i + 1]`。 如果不同，则打印`NO`立即地。 一个无效的转换足以使整个字符串变得不美观，因此检查后面的字符无法改变答案。 
5. 如果每个相邻对都通过了检查，则打印`YES`。 此时，完整字符串中的每个转换都是有效的。 

### 为什么它有效

 不变量是在处理完第一个之后`i`过渡，第一个过渡之间的每个过渡`i + 1`字符有效。 当检查下一对时，算法会在该对违反定义时准确拒绝。 如果它不拒绝，则不变量扩展到下一对。 毕竟`n - 1`转换已经处理完毕，每个相邻的对都是有效的，这正是雄伟字符串的定义。 因此该算法完全接受有效的字符串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    for i in range(len(s) - 1):
        current = ord(s[i]) - ord('a')
        expected = (current + 1) % 26
        actual = ord(s[i + 1]) - ord('a')

        if actual != expected:
            print("NO")
            return

    print("YES")

if __name__ == "__main__":
    solve()
```该循环直接对应于算法中的相邻对扫描。`ord(s[i]) - ord('a')`地图`a`通过`z`到`0`通过`25`。 加一并取模 26 可以处理两种普通的转换，例如`c -> d`，以及特殊的过渡`z -> a`。 

范围结束于`len(s) - 1`因为最后一个字符后面没有字符。 使用`range(len(s))`会尝试访问`s[i + 1]`什么时候`i`是最终索引并导致越界错误。 

单字符情况自然有效，因为循环执行零次并且算法打印`YES`。 不需要专门的分支。 

Python 整数不会溢出，并且执行的唯一算术是对来自`0`通过`25`。 该解决方案也会在第一个无效转换处停止，尽管其最坏情况的复杂性仍然是线性的。

# helper: run solution on input string, return output string
import sys
import io

def solve():
    s = input().strip()

    for i in range(len(s) - 1):
        current = ord(s[i]) - ord('a')
        expected = (current + 1) % 26
        actual = ord(s[i + 1]) - ord('a')

        if actual != expected:
            print("NO")
            return

    print("YES")

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        output = io.StringIO()
        old_stdout = sys.stdout
        sys.stdout = output
        try:
            solve()
        finally:
            sys.stdout = old_stdout
        return output.getvalue()
    finally:
        sys.stdin = old_stdin
        input = old_input

# provided samples
assert run("cdefghij\n") == "YES\n", "sample 1"
assert run("tuvwxyzab\n") == "YES\n", "sample 2"
assert run("hellllo\n") == "NO\n", "sample 3"

# minimum-size input
assert run("a\n") == "YES\n", "single character has no invalid transition"

# all-equal values
assert run("aaaaa\n") == "NO\n", "equal consecutive characters are invalid"

# wraparound at z -> a
assert run("xyzab\n") == "YES\n", "alphabet must wrap around"

# invalid transition at the final pair
assert run("abcdefgq\n") == "NO\n", "invalid transition at the end"

# large input
large = "a" + "bcdefghijklmnopqrstuvwxyz" * 4000
assert run(large + "\n") == "NO\n", "large input with a boundary mismatch"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 |`a`|`YES`| 最小尺寸输入和零相邻对 |
 |`aaaaa`|`NO`| 重复字符被拒绝 |
 |`xyzab`|`YES`| 正确的`z -> a`概括|
 |`abcdefgq`|`NO`| 最终比较时检测到不匹配 |
 | 大型构造弦 |`NO`| 线性扫描在大输入上仍然实用 |

 ## 边缘情况

 单字符输入`a`由精确的输入处理`a\n`。 该循环没有迭代，因为没有相邻对。 算法打印`YES`，直接从定义得出：不存在违反规则的转换。 

环绕式案例`xyzab`练习简单的角色价值比较经常处理不当的转变。 执行的相关部分是`x -> y`,`y -> z`,`z -> a`， 和`a -> b`。 为了`z`，从零开始的值为`25`， 所以`(25 + 1) % 26`变成`0`，对应于`a`。 每对都通过，结果是`YES`。 

重复字符的情况`aaaaa`第一次比较失败。 当前角色是`a`，其所需的后继者是`b`，而实际的下一个字符是`a`。 该算法立即打印`NO`，而不是错误地将字符串视为按字母顺序非递减。 

最后，`abcdefgq`表明该实现不仅仅检查前缀。 前六个转换是有效的，但是`g -> q`无效。 扫描到达最后一对，检测不匹配并打印`NO`。 这就是为什么有必要检查每个相邻对，而不是在确认初始增加运行后停止。
