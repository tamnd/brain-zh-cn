 ## 解决方案
 ## 问题理解

 当一个正整数可以被它的十进制数字之和整除时，它被称为“俗气”。 例如，数字`360`加起来为`9`， 和`360 % 9 == 0`， 所以`360`很俗气。 为了`87`，数字和为`15`， 但`87 % 15 != 0`，所以它并不俗气。 任务只是打印`YES`当条件成立并且`NO`否则。 

输入包含一个正整数`n`。 该声明保证`n`适合Java`int`， 所以`n`至多是`2,147,483,647`。 这意味着十进制表示最多有 10 位数字。 我们不需要复杂度取决于数值的算法`n`，因为即使是最大的输入也只包含少数数字。 

关键的边缘情况很小，但对于捕获粗心的实现很有用。 用于输入`7`，数字和为`7`， 和`7 % 7 == 0`，所以输出是`YES`。 只考虑多位数字的解决方案在这里会失败。 

用于输入`10`，数字和为`1`，并且每个整数都可以被整除`1`，所以正确的输出是`YES`。 一个常见的错误是将位数与数字总和混淆并错误地拒绝它。 

用于输入`11`，数字和为`2`， 但`11 % 2 == 1`，所以输出是`NO`。 这会捕获意外检查数字和是否整除其中一位数字而不是整个数字的实现。 

## 方法

 最直接的暴力方法是尝试每一个可能的正除数`n`。 对于每位候选人`d`，我们可以测试是否`n % d == 0`，并以某种方式确定数字和是否在这些除数之中。 一个更简单的版本首先计算数字和，然后通过重复考虑候选者来测试整除性`n`。 这是正确的，因为最终会检查数字和本身，但在最坏的情况下，它的性能约为`n`可分性检查。 自从`n`可以大到`2,147,483,647`，这超过了 20 亿次模运算，这远远超出了一秒程序所能承受的范围。 

蛮力方法之所以有效，是因为整除性正是定义要求我们检查的内容，但它忽略了除数已经完全由数字确定的事实`n`。 我们不需要寻找它。 

关键的观察是所需的除数只是数字之和。 我们可以通过重复取最后一位数字来获得该总和`n % 10`并用整数除以删除该数字`10`。 一旦知道总和，进行一次模运算，`n % digit_sum`，给出答案。 

因为`n`最多有 10 个小数位，数字处理迭代次数最多为 10。因此，最佳算法实际上是给定整数范围下的恒定时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取整数`n`并保持其原有的价值。 我们在最终的整除性检查中需要原始数字，因此提取数字时使用的值不得永久覆盖它。 
2. 设置`digit_sum`为零并使用重复提取最后一个小数位`n % 10`。 将该数字添加到`digit_sum`，然后将其删除`n //= 10`。 每次迭代只处理一位十进制数字。 
3、处理完所有数字后，测试原数是否能被整除`digit_sum`。 如果余数为零，则打印`YES`; 否则，打印`NO`。 
4. 由于输入为正，因此数字和也为正。 没有被零除的情况需要处理。 

### 为什么它有效

 数字提取循环将原始数字的每个十进制数字精确地添加一次，因此当它完成时，`digit_sum`正是由俗气数的定义指定的除数。 最终测试准确检查原始数字是否可以被该总和整除。 因此`YES`完全打印出俗气的数字，并且`NO`为每个其他正整数打印。 

## Python 解决方案```python
Pythonimport sysinput = sys.stdin.readline

def solve():    n = int(input())    original = n
    digit_sum = 0    while n > 0:        digit_sum += n % 10        n //= 10
    if original % digit_sum == 0:        print("YES")    else:        print("NO")

if __name__ == "__main__":    solve()
```变量`original`保留输入，因为数字提取循环反复减少`n`为零。 如果没有单独的副本，最终的可分性测试将错误地测试`0 % digit_sum`。 

表达式`n % 10`获取最后一个小数位，同时`n // 10`将其删除。 这里需要整数除法，因为我们使用的是十进制数字而不是浮点值。 

循环使用`while n > 0`，这已经足够了，因为输入保证为正。 提取出最后一位数字后，`n`变为零并且循环停止。 

Python 整数不存在固定宽度整数语言所存在的溢出问题，尽管该问题的界限对于 32 位有符号整数来说已经足够小了。

 ## 边缘情况

 对于个位数输入`7`，算法提取`7`, 给予`digit_sum = 7`。 原值也是`7`， 所以`7 % 7 == 0`输出是`YES`。 这是有效的，因为一个正的个位数总是能被它自己的数字和整除。 

为了`10`，算法提取`0`进而`1`，产生数字和`1`。 最终测试是`10 % 1 == 0`，所以输出是`YES`。 零数字不会引起问题，因为它对总和的贡献为零。 

为了`11`，两个提取的数字产生`digit_sum = 2`。 最终测试是`11 % 2`，即`1`，所以输出是`NO`。 这证实了该算法测试的是整个数字和的整除性，而不是仅仅检查单个数字的属性。 

对于最大允许输入，`2147483647`，数字和为`46`。 该算法仅执行 10 次提取迭代，然后评估`2147483647 % 46`，它是非零的，所以输出是`NO`。 数字的大小不会以任何有意义的方式使算法变慢，因为十进制位数仍然有限。
