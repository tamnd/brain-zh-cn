 ## 解决方案
 ## 问题理解

 该任务是对计算机硬盘容量的直接分类。 输入是一个字符串，例如`300GB`，其中数字部分是以 GB 为单位的容量，最后的`GB`是固定后缀。 我们必须删除该后缀，将剩余部分解释为整数，并将容量分为三个类别之一。 

最大容量为 200 GB`SMALL`。 容量大于200GB但最多500GB`MEDIUM`。 任何超过 500 GB 的内容都是`LARGE`。 官方问题使用 1 秒时间限制和 256 MB 内存。 由于只有一个短输入字符串，并且计算包括解析它并最多执行两次比较，因此该算法完全在这些限制之内。 运行时间仅与输入字符串中的字符数成正比。 

主要的边界情况是两个阈值本身。 为了`200GB`，答案是`SMALL`， 不是`MEDIUM`，因为第一个区间包含在内。 为了`500GB`，答案是`MEDIUM`， 不是`LARGE`，因为第二个区间也包含在内。 例如，输入`200GB`产生`SMALL`， 尽管`500GB`产生`MEDIUM`。 粗心的实现使用`< 200`或者`< 500`会对这些精确的边界值进行错误分类。 

另一个容易犯的错误是将完整字符串与诸如此类的字符串进行比较`"200GB"`无需首先解释其数字部分。 字典序字符串比较一般不代表数值比较。 例如，`"1000GB"`和`"500GB"`在我们需要的逻辑下没有相同的顺序。 提取整数可以避免整类错误。 

## 方法

 强力解释是模拟从最小可能值到给定容量的每个可能容量，并确定哪个区间包含它。 从模拟值最终达到实际容量的意义上来说，这是正确的，但它每 GB 执行一次迭代。 如果容量是`C`，该方法执行`C`迭代次数，因此其最坏情况操作计数与最大可能容量成正比，而不是与输入长度成正比。 没有理由枚举值，因为分类完全由两个固定边界确定。 

关键的观察结果是这三个类别形成连续的区间。 一旦知道了数字容量，就只有两个问题需要回答：是否最多为 200，如果不是，是否最多为 500？ 第一个真实条件完全决定了答案。 如果两个条件都不成立，则容量必须大于 500，因此`LARGE`。 

暴力破解之所以有效，是因为它最终会发现包含容量的相同区间，但会失败，因为它对对结果没有影响的值进行了不必要的工作。 只有两个阈值重要的观察结果将问题简化为解析一个整数并进行两次恒定时间比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(C)| O(1) | O(1) | 原则上太慢|
 | 最佳 | O(L) | O(1) | O(1) | 已接受 |

 这里，`C`是数字容量，`L`是输入字符串的长度。 对于问题所使用的小固定大小输入，最佳解决方案实际上是恒定时间。 

## 算法演练

 1.读取容量字符串，例如`450GB`。 这`GB`后缀不是数值的一部分，因此在将容量转换为整数之前必须将其删除。 
2. 将最后两个字符之前的所有内容转换为整数。 为了`450GB`，这给出了`450`。 
3.如果容量最多`200`， 打印`SMALL`。 比较必须包含在内，因为 200 GB 正好属于此类别。 
4. 否则，如果容量最多为`500`， 打印`MEDIUM`。 到达这个分支已经告诉我们容量大于 200，所以结果间隔正好是`201`通过`500`。 
5. 如果比较均不成功，则打印`LARGE`。 此时容量必然大于500。 

为什么有效：删除后`GB`，每个有效容量都由一个整数表示。 三个可能的输出将所有容量划分为`x <= 200`,`200 < x <= 500`， 和`x > 500`。 该算法按顺序检查这些间隔，因此只有一个分支与数字容量匹配，并打印相应的分类。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    capacity = int(s[:-2])

    if capacity <= 200:
        print("SMALL")
    elif capacity <= 500:
        print("MEDIUM")
    else:
        print("LARGE")

if __name__ == "__main__":
    solve()
```里面第一行`solve`读取完整的输入并删除尾随的换行符`strip()`。 表达式`s[:-2]`恰好删除两个字符`GB`，只留下容量的小数表示。 

蟒蛇的`int`执行所需的数值转换，因此比较如`capacity <= 200`是数字而不是字典顺序。 

第一个条件使用`<= 200`，匹配包含的较低类别边界。 第二个条件只需要检查`<= 500`因为较早的`if`已经排除了最多 200 的每个值。最终`else`因此代表每个大于 500 的值。 

Python 中不存在整数溢出问题，算法仅存储输入字符串和一个整数。

 ## 边缘情况

 第一个边界情况正好是`200GB`。 算法解析`200`, 检查`200 <= 200`，并立即打印`SMALL`。 一个实现使用`< 200`将错误地继续到下一个类别。 

第二个边界情况正好是`500GB`。 第一次比较失败是因为`500`大于`200`，而第二个比较成功是因为`500 <= 500`。 输出是`MEDIUM`。 使用`< 500`这里会错误地将其分类为`LARGE`。 

紧邻第二个边界上方的值，`501GB`，遵循相反的路径。`501 <= 200`是假的并且`501 <= 500`也是假的，所以最后的分支打印`LARGE`。 这证实了两者之间不存在差距。`MEDIUM`和`LARGE`范围。 

最后，在转换之前必须删除后缀。 为了`450GB`,`s[:-2]`产生`450`， 哪个`int`转换为数字 450。然后，算法将该数字与数字阈值进行比较，而不是尝试推理原始文本。
