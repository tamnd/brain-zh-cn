 ## 问题理解

 该任务是单位圆的直接应用。 输入是以度为单位的一个整数角度，介于 0 到 359 之间（包括 0 和 359）。 想象一下将正 x 轴逆时针旋转该角度所获得的射线。 它与单位圆的交点有坐标

 (cosθ,sinθ)。 

需要的输出只是x坐标，所以我们需要打印cosθ。 输入以度为单位，而 Python 的三角函数需要弧度，因此必须首先使用以下方法转换角度

 θ rad​=θ deg​180 π​。 

输入范围小意味着没有算法难度。 仅需要处理一个整数，最多有 360 个可能的值。 即使是恒定时间的数学库调用也完全在限制范围内。 官方问题给出了1秒的时间限制和256 MB的内存，因此不需要任何预计算或近似方案。 

主要的边缘情况来自余弦在数学上精确已知的角度，但浮点算术可能会稍微不同地表示该值。 例如，```
0
```对应于点 (1,0)，因此正确的 x 坐标为 1。如果不小心将度数错误地转换为弧度，可能会产生与 1 不同的值。 

另一个边界情况是```
180
```其点是(−1,0)，所以答案是−1。 忘记余弦在第二和第三象限中改变符号的解决方案可能会错误地打印正值。 

直角回转案例也很有用：```
90
```从数学上来说，答案是 0。使用浮点实现`cos(pi / 2)`可能会产生一个很小的值，例如 6.123233995736766e−17，而不是恰好为零。 这仍然是正常浮点比较容差内的正确数值答案，并且法官相应地接受浮点输出。 

最后，最大允许角度，```
359
```距离完整旋转仅差一度。 它的余弦为正且非常接近 1。将 359 视为 360 会默默地产生错误的结果。 

## 方法

 字面上的强力方法可以存储从 0 到 359 的每个整数角度的余弦，然后查找请求的值。 构建这样的表需要 360 次余弦计算，并且随后查找答案需要恒定的时间。 如果我们想象对表进行简单的顺序搜索，最坏的情况需要 360 次比较，或者 359 次失败的比较，然后才是最终匹配。 对于此问题来说，这已经足够快了，因为该域仅包含 360 个可能的角度。 

然而，这种方法完全忽略了任务的数学结构。 单位圆上的 x 坐标直接由余弦定义。 不需要枚举可能的角度，因为输入本身已经是我们需要的角度。 暴力方法之所以有效，是因为域很小，但它增加了不必要的存储和计算。 观察到所需的坐标恰好是 cos(θ)，从而将整个问题简化为一度到弧度的转换和一次库调用。 

| 方法| 时间复杂度| 空间复杂度| 判决 |

 | 蛮力 | O(360)，实际上是 O(1) | O(360) | 已接受，但没有必要 |

 ## 算法演练

 1. 读取整数角度（以度为单位）。 由于问题包含单个测试用例，因此只有一个值。 
2. 使用以下命令将角度从度数转换为弧度`angle * pi / 180`。 这是必要的，因为 Python 的`math.cos`函数使用弧度。 
3. 计算转换角度的余弦。 在单位圆上，余弦正是对应点的x坐标。 
4. 打印生成的浮点值。 不需要手动舍入，因为允许输出为浮点数。 

### 为什么它有效

 对于每个角度 θ，相应的射线与单位圆相交的点是 (cosθ,sinθ)。 该问题专门要求 x 坐标，因此该坐标恰好是 cosθ。 编程语言所需的唯一表示更改是在调用余弦函数之前将输入从度数转换为弧度。 因此，该算法可以精确计算所需的数学量。 

## Python 解决方案```python
Pythonimport sysimport math
input = sys.stdin.readline
angle = int(input())radians = angle * math.pi / 180.0answer = math.cos(radians)
print(answer)
```一线进口`sys`对于所请求的快速输入约定和`math`为余弦函数和常数 π。 

输入是一个整数，所以`int(input())`就足够了。 不存在循环，因为问题仅包含一个角度。 

表达式`angle * math.pi / 180.0`执行度数到弧度的转换。 这里使用浮点运算是必要的，因为弧度通常不是整数。`math.cos`然后直接计算x坐标。 Python 的浮点表示可能会在零等值附近产生微小误差，但这些都是正常的浮点近似值，并且完全在浮点输出问题的预期容差范围内。 

不存在整数溢出问题，因为角度最多为 359，并且 Python 整数也会自动增长。 没有边界索引计算或迭代，因此在实现中不存在相差一的问题。

 ## 边缘情况

 对于角度 0，准确的输入是```
0
```该算法将其转换为 0 弧度并计算 cos0=1，产生`1.0`。 基于象限的手动实现很容易在这里引入不必要的特殊情况，而直接公式可以自然地处理它。 

对于 180 度角，输入为```
180
```转换后的角度为 π，并且`math.cos(pi)`回报`-1.0`。 算法演练中的不变量被保留，因为余弦已经编码了每个象限中 x 坐标的正确符号。 

对于 90 度角，输入为```
90
```数学答案是零。 浮点库可能返回一个非常接近零的值，而不是恰好为零，因为 π/2 无法用二进制浮点精确表示。 该程序不会舍入或截断该值，这避免了在解决方案中引入任意精度策略。 法官的浮点比较将微小的数值误差视为等于零。 

对于上边界，输入是```
359
```该算法将其转换为 359π/180 弧度并计算出大约 0.9998476951563913。 这与 360 度的答案不同，后者恰好为 1。输入限制以 359 结束，因此程序正确处理提供的角度，而不是将其减小到附近的基本方向。
