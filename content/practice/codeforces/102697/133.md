 ## 解决方案
 ## 问题理解

 任务故意简单。 我们收到一个字符串，代表一行文本，并且必须决定该行是否应被视为问题。 该定义纯粹是语法上的：字符串的最后一个字符必须是`?`。 如果是，我们打印`YES`; 否则我们打印`NO`。 官方问题指定了单个输入字符串和一秒 256 MB 的限制。 

关键区别在于文本中某处出现的问号和最后一个字符的问号。 例如，`Is this?`是一个问题，同时`Is this? really`不是，因为最终的字符是`y`。 

这里没有有意义的大数值约束，因为输入由一个字符串组成。 运行时间自然与必须读取的输入量成正比。 即使字符串很长，检查每个字符的算法在输入大小上仍然是线性的，并且很容易满足普通输入大小规定的时间限制。 更重要的是，我们可以避免在读取后检查整个字符串，因为答案仅取决于一个字符。 

第一个边缘情况是仅包含问号的字符串。```
?
```正确的输出是`YES`。 一个粗心的实现，期望问号有另一个字符，然后才能拒绝这个有效的情况。 

第二个边缘情况是出现在结尾之前的问号。```
hello? world
```正确的输出是`NO`。 搜索字符串是否存在`?`会错误地返回`YES`，因为问号不是最终字符。 

第三种边缘情况涉及尾随空格。```
hello?
```正确的结果是`NO`如果尾随空格实际上是输入字符串的一部分，因为最后一个字符是空格而不是`?`。 这就是为什么实现应该保留输入行的有意义的内容而不是盲目地搜索问号。 在Python中，`rstrip('\n')`删除行结尾，同时保留其他尾随字符。 

## 方法

 一种简单的暴力解释是扫描每个字符并确定哪个是最终字符。 这是正确的，因为处理完整的字符串后，遇到的最后一个字符正是控制答案的字符。 对于一个长度的字符串`L`，这执行`L`最坏情况下的字符检查。 

这里不存在真正的性能故障。 输入本身包含`L`字符，所以阅读它已经花费了`O(L)`时间。 因此，如果我们计算输入处理，则完整扫描是渐近最优的。 读取字符串后唯一可用的改进是避免扫描并直接检查其最终字符。 

有用的观察结果是，该问题不包含影响答案的字符串中间的信息。 一旦输入行被读取，仅`s[-1]`很重要。 因此，我们可以用一种直接的字符比较来代替全面扫描。 

暴力扫描之所以有效，是因为它最终会发现最终字符，但它对不会影响结果的字符执行工作。 答案仅取决于最终位置的观察使我们可以将后输入计算减少为`O(1)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(L) | O(1) | O(1) | 已接受 |
 | 最佳 | O(L) 包括输入，O(1) 输入后 | O(1) | O(1) | 已接受 |

 这里`L`是输入字符串的长度。 这两种方法之间的区别主要是教育性的，而不是针对这个问题的实用性，因为输入读取已经花费了线性时间。 

## 算法演练

 1. 读取整个输入行并仅删除其换行符。 我们保持其他字符不变，因为实际的最终字符决定了答案。 
2. 使用以下命令访问最终字符`s[-1]`。 Python的负索引直接给出最后位置的字符，因此不需要扫描字符串。 
3. 将该字符与`?`。 如果相等，则打印`YES`; 否则，打印`NO`。 

### 为什么它有效

 该算法准确检查问题定义中使用的属性：最终字符是否是`?`。 如果`s[-1] == '?'`，字符串满足定义并且算法打印`YES`。 如果`s[-1] != '?'`，不满足定义，算法打印`NO`。 没有其他角色可以改变这个决定，因此检查最终角色就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().rstrip('\n')

print("YES" if s[-1] == '?' else "NO")
```输入被读取`input()`，其中包括存在的换行符。 我们完全删除该换行符`rstrip('\n')`。 使用`strip()`会不太精确，因为它还会从字符串末尾删除空格和其他空白，可能会改变最终字符的实际含义。 

表达式`s[-1]`直接访问最后一个字符。 这可以避免字符串上不必要的循环。 

在选择输出之前执行比较。 产生一个问号`YES`，并且每个其他最终字符都会产生`NO`。 

该问题保证输入字符串有效，因此访问`s[-1]`是安全的。 没有整数运算，因此整数溢出是无关紧要的，并且不存在涉及可能引入差一错误的显式长度的索引计算。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|

## 测试用例```python
import sys
import io

def solve():
    input = sys.stdin.readline
    s = input().rstrip('\n')
    print("YES" if s[-1] == '?' else "NO")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("Welcome to the CodeRams contest?\n") == "YES\n", "sample 1"
assert run("We hope you like the problems!\n") == "NO\n", "sample 2"
assert run("Good luck today\n") == "NO\n", "sample 3"

# Minimum-size meaningful input
assert run("?\n") == "YES\n", "single question mark"

# All characters are ordinary text
assert run("hello\n") == "NO\n", "ordinary word"

# Question mark appears internally but is not final
assert run("hello? world\n") == "NO\n", "question mark not at end"

# Boundary case with a trailing space
assert run("hello? \n") == "NO\n", "trailing space changes final character"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 |`?`|`YES`| 最小尺寸的有意义输入和直接最终字符访问 |
 |`hello`|`NO`| 没有问号的普通文本 |
 |`hello? world`|`NO`| 防止混淆存在`?`和`?`最后|
 |`hello? `|`NO`| 检查尾随字符是否不会被意外丢弃 |

 ## 边缘情况

 对于单字符输入`?`，字符串的长度为一并且`s[-1]`是同样的问号吗？ 比较成功，输出为`YES`。 假设字符串必须包含多个字符的解决方案在这里会失败。 

为了`hello? world`，存在问号，但后跟一个空格和更多文本。 该算法从不搜索字符串中任何位置的问号。 它只读`s[-1]`，即`d`，所以它正确打印`NO`。 

对于诸如这样的输入`hello? `，最后一个字符是空格。 实现使用`rstrip('\n')`而不是`strip()`，因此空格仍然是字符串的一部分。 最后`s[-1]`是空间，答案是`NO`。 

中心不变量很简单：在产生答案的那一刻，被比较的字符正是输入行的最后一个字符。 由于问题的定义完全取决于该字符，因此每个可能的有效字符串都会被正确分类。
