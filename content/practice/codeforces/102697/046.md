 ## 解决方案
 ## 问题理解

 任务是将两个非负整数相加，其表示形式为二进制字符串。 第一行包含一个二进制数，第二行包含另一个二进制数，所需的输出是它们的和，也以二进制形式编写。 字符串可以有不同的长度，因此加法必须将缺失的高位数字处理为零。 

例如，输入```
101
11
```代表(5)和(3)。 它们的和为(8)，其二进制表示为`1000`。 

该语句没有指定两个字符串长度的数字上限。 由于数字直接表示为字符串，因此即使二进制值本身对于固定宽度整数类型来说太大，预期的方法也应该有效。 将数字存储在机器整数中的解决方案将不必要地施加输入未施加的大小限制。 线性时间解决方案是自然目标，因为每个输入数字都可能影响进位传播并且必须进行潜在检查。 

有一些边缘情况，粗心的实施可能会处理不当。 首先，数字可以有不同的长度。 例如，```
1
111
```有输出```
1000
```因为第一个数字的缺失数字被视为零。 仅在两个字符串仍具有数字时处理位置的实现会过早停止并丢失前导进位。 

第二个边缘情况是最终进位。 为了```
1
1
```正确的输出是```
10
```处理完唯一的一对输入数字后，进位仍然是1，因此它必须成为新的最高有效数字。 仅打印已处理位置的实现会错误地生成`0`。 

如果输入被视为正常的十进制整数表示，则前导零是另一个可能的麻烦来源。 例如，```
00101
0011
```表示 (5+3=8)，所以输出应该是```
01000
```如果该操作被理解为保留输入表示的宽度，但“以二进制形式返回总和”的通常解释是规范表示，`1000`。 下面的安全实现直接执行二进制加法，自然地生成规范形式，而不依赖于具有相等长度的输入字符串。 

## 方法

 思考该任务的一种强力方法是枚举可能的数值并搜索正确的总和。 如果较长的输入有 (L) 个二进制数字，则表示的数字可以大到 (2^L-1)。 考虑达到该量值的每个可能值的搜索可能需要 (\Theta(2^L)) 个候选，甚至检查候选的二进制表示成本高达 (O(L))。 在最坏的情况下，给出 (\Theta(L2^L)) 工作，仅在几十个输入位之后就变得不可行。 蛮力方法是正确的，因为最终它考虑实际和，但它忽略了二进制加法具有非常小的局部状态这一事实。 

关键的观察是每个二进制列仅取决于三个值：两个输入位和来自较低有效列的进位。 对于带有传入进位 (c) 的两位 (a) 和 (b)，结果数字为

 [
 (a+b+c)\bmod 2
 ]

 输出进位是

 [
 \left\lfloor\frac{a+b+c}{2}\right\rfloor。 
]

 只有四对可能的输入位和两个可能的进位值，因此不需要全局搜索。 我们可以重现与普通纸笔加法完全相同的过程，从最低有效数字开始并向左移动。 

暴力破解之所以有效，是因为它会搜索可能结果的整个空间，但会失败，因为该空间随着位数呈指数增长。 二进制加法列仅取决于当前位和一个进位的观察结果将问题简化为对输入的单次传递。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(L2^L)) | (O(L)) | 太慢了 |
 | 二进制加法 | (O(L)) | (O(L)) | 已接受 |

 这里 (L=\max(|a|,|b|))。 

## 算法演练

 1. 读取两个二进制字符串并将两个索引设置为其最后位置。 我们从右边开始，因为最低有效数字是其总和已知且不需要另一列进位的第一个数字。 
2. 将初始进位设置为零。 最低有效位置的右侧没有数字，因此没有进位进入第一个加法。 
3. 当任一字符串仍有未处理的数字或仍有进位时，从每个字符串中读取当前数字。 如果索引已移动到其字符串开头之前，请改用零。 即使两个数字的长度不同，这也会按其最低有效位对齐两个数字。 
4. 计算`total = a_digit + b_digit + carry`。 输出位是`total % 2`，而下一个进位是`total // 2`。 自从`total`只能是 0、1、2 或 3，进位始终为零或一。 
5. 将生成的位附加到结果列表中。 这些数字是从最低有效位到最高有效位生成的，因此该列表当前相对于正常表示是相反的。 
6. 将两个索引向左移动一位并继续，直到没有输入数字且没有进位剩余。 
7. 反转结果并打印。 反转恢复了通常的最高有效位优先表示。 

### 为什么它有效

 处理完任何位置后，算法存储的进位正是普通二进制加法将发送到下一个位置的进位。 对于当前位置，该算法使用实际输入位（如果存在）、零（缺失位）以及精确的传入进​​位。 因此，计算出的模二余数是该位置的唯一有效输出位，整数除以二给出唯一有效的传出进位。 通过从最低有效位置到最高有效位置的归纳，每个产生的数字都是正确的。 当所有输入数字都已消耗完时，如果仍有进位，则处理将继续，因此最终的前导`1`永远不会丢失。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def add_binary(a: str, b: str) -> str:
    i = len(a) - 1
    j = len(b) - 1
    carry = 0
    result = []

    while i >= 0 or j >= 0 or carry:
        x = ord(a[i]) - ord('0') if i >= 0 else 0
        y = ord(b[j]) - ord('0') if j >= 0 else 0

        total = x + y + carry
        result.append(str(total & 1))
        carry = total >> 1

        i -= 1
        j -= 1

    return ''.join(reversed(result))

def main():
    a = input().strip()
    b = input().strip()
    print(add_binary(a, b))

if __name__ == "__main__":
    main()
```这两个索引从每个字符串的最后一个字符开始，对应于 (2^0) 位置。 每次迭代恰好消耗右侧的一列。 

条件表达式为`x`和`y`是允许添加不等长字符串的。 一旦索引变为负数，相应的数字对每个剩余列的贡献为零。 

位计算使用`total & 1`，这相当于`total % 2`， 和`total >> 1`，这相当于这些非负值的整数除以二。 这两个表达式都直接反映正在执行的二进制算术。 

结果存储为字符，而不是将任一输入转换为 Python 整数。 这避免了对数值大小的依赖，并使算法与输入位数成比例。 

不存在整数溢出问题，因为该算法从不将任何潜在的巨大二进制数存储为机器大小的整数。 唯一的数字变量是各个位、进位及其总和。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O(L)) | 每个输入数字被处理一次，其中 (L=\max( | a | , | b | ))。 |
 | 空间| (O(L)) | 输出最多包含 (L+1) 位，结果列表存储反转之前的这些位。 |

 线性复杂度在常数因子范围内是最佳的，因为算法必须至少读取输入数字。 即使字符串非常长，工作量也只会与其长度成正比增长，而暴力搜索则呈指数级增长。

import sys
import io

def add_binary(a: str, b: str) -> str:
    i = len(a) - 1
    j = len(b) - 1
    carry = 0
    result = []

    while i >= 0 or j >= 0 or carry:
        x = ord(a[i]) - ord('0') if i >= 0 else 0
        y = ord(b[j]) - ord('0') if j >= 0 else 0

        total = x + y + carry
        result.append(str(total & 1))
        carry = total >> 1

        i -= 1
        j -= 1

    return ''.join(reversed(result))

def solve():
    a = input().strip()
    b = input().strip()
    return add_binary(a, b)

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        return solve() + "\n"
    finally:
        sys.stdin = old_stdin
        input = old_input

# Provided sample
assert run("101\n11\n") == "1000\n", "sample 1"

# Minimum-size inputs
assert run("0\n0\n") == "0\n", "minimum values"

# Final carry
assert run("1\n1\n") == "10\n", "final carry"

# Unequal lengths
assert run("1\n111\n") == "1000\n", "different lengths"

# All equal digits
assert run("111111\n111111\n") == "1111110\n", "all ones"

# Leading zeroes
assert run("00101\n0011\n") == "1000\n", "leading zeroes"

n = 10000
assert run("1" * n + "\n" + "1\n") == "1" + "0" * (n - 1) + "0\n", "large input"

## 边缘情况

 对于不等长度，请考虑确切的输入```
1
111
```第一次迭代加 (1+1)，产生带进位 1 的 0。 第二次迭代使用零作为缺少的第一个数字，并添加 (0+1+1=2)，再次产生带有进位 1 的零。 第三次迭代的行为相同，剩余的进位产生前导进位。 最终结果是`1000`。 对耗尽字符串的显式零替换使得该方法无需特殊情况即可工作。 

对于最终进位，请考虑```
1
1
```唯一的输入列给出 (1+1=2)，因此输出位为零，进位变为 1。 现在两个输入索引都已耗尽，但循环条件仍然看到非零进位。 再一次迭代输出 1，给出`10`。 没有`or carry`在循环条件下，实现将错误地返回`0`。 

对于长进位传播，请考虑```
1111
1
```最低有效列产生零和进位。 接下来的每一列都会将该进位添加到`1`，产生另一个零和另一个进位。 在第四个输入数字之后，进位仍然是 1，因此第五次迭代会产生前导一位。 结果是`10000`。 这种情况最有可能暴露出错误处理从输入数字到最终进位的转换的实现。 

对于前导零，请考虑```
00101
0011
```该算法完全按照编写的方式处理字符串。 前导零最终构成包含零位的列，而有效后缀表示 (5+3)。 生成的结果是`1000`，这是总和的规范二进制表示。 不需要转换为固定宽度整数或修剪逻辑。
