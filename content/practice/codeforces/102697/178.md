 ## 解决方案
 ## 问题理解

 任务是确定给定的正整数是否能被 2 整除。如果是，我们打印`YES`; 否则，我们打印`NO`。 输入恰好包含一个正整数，并且不存在多个测试用例。 所需的输出是一个单词，描述该数字是否是二的倍数。 

该声明没有公布该整数的数值上限。 时间限制为 1 秒，内存限制为 256 MB。 由于所需的属性仅取决于能否被 2 整除，因此整数的大小不需要我们执行与其值成比例的算术运算。 我们可以直接检查它的十进制表示形式，对位数进行恒定的工作。 如果输入非常长，这也比构造 Python 整数更安全。 

关键的边缘情况是小值和最后一位数字为零的值。 例如，输入`1`必须产生`NO`，因为 1 不能被 2 整除。仅检查数字是否为正数的粗心实现会错误地接受它。 输入`2`必须产生`YES`，因为 2 本身是 2 的最小正倍数。 输入`10`必须产生`YES`，即使它的最后一位数字为零而不是另一个偶数。 基于最后一位数字的检查可以直接处理所有三种情况。 

## 方法

 一种简单的暴力方法会通过重复考虑可能的二的倍数来尝试确定该数字是否具有偶数商。 更简单的暴力解释是枚举从 2 到给定数字的整数，并检查哪些是 2 的倍数，在达到输入时停止。 这是正确的，因为每个二的正倍数都出现在该序列中，但它执行`n - 1`输入值的迭代`n`。 如果`n`很大，这比问题所需的工作量要多得多，并且该语句给出了不小的上限，使这种枚举变得合理。 

十进制记数法的结构给出了更强有力的观察。 当十进制整数的最后一位是以下之一时，它恰好可以被 2 整除`0`,`2`,`4`,`6`， 或者`8`。 我们不需要检查任何较早的数字。 例如，`123456`是偶数，因为它的最后一位数字是`6`， 尽管`987653`是奇数，因为它的最后一位数字是`3`。 蛮力方法之所以有效，是因为它最终通过重复算术发现了整除性，但失败了，因为它忽略了十进制表示的这个局部属性。 仅查看最后一位数字可将问题简化为一个字符检查。 

因此，如果输入适合机器整数，则最佳方法是数学意义上的恒定时间，并且`O(L)`在严格的输入大小意义上如果`L`是十进制位数，因为读取输入本身需要`O(L)`时间。 读取输入后的实际决定需要`O(1)`时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 对于大 n 来说太慢 |
 | 最后一位数字 | O(L) 包括输入读取 | 输入字符串的 O(L) | 已接受 |

 ## 算法演练

 1. 将正整数作为字符串读取。 直接读取十进制表示形式可以避免依赖于特定的整数大小。 
2. 取出字符串的最后一个字符。 能否被 2 整除仅取决于该数字，因此不需要处理数字的其他部分。 
3. 检查最后一位是否属于`02468`。 如果是，则打印`YES`; 否则，打印`NO`。 
4. 在该单一隶属度测试之后立即确定结果，因此不存在候选倍数的循环、除法或枚举。 

为什么有效：每个十进制整数当其个位数为偶数时恰好为偶数。 可能的偶数小数位是`0`,`2`,`4`,`6`， 和`8`。 因此，该算法准确地接受可被 2 整除的正整数，并准确地拒绝那些不能被 2 整除的正整数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = input().strip()

    if n[-1] in "02468":
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```该解决方案将输入读取为字符串，而不是使用`int`。 唯一重要的角色是`n[-1]`，这是个位数。 会员资格`"02468"`是一个恒定大小的检查。 

使用字符串还可以处理任意长的十进制输入，而不依赖于 Python 的整数转换限制。 该问题仅询问能否被二整除，因此转换整个值不会提供任何有用的信息。 

该算法中不存在差一边界，因为输入保证为正整数，因此字符串始终包含至少一位数字。 价值`0`在规定的输入条件下不需要特殊处理。

import io

def solve():
    n = input().strip()
    if n[-1] in "02468":
        print("YES")

    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        old_stdout = sys.stdout
        sys.stdout = io.StringIO()
        solve()
        output = sys.stdout.getvalue()
        sys.stdout = old_stdout
    finally:
        sys.stdin = old_stdin
        input = old_input

    return output

 ## 边缘情况

 输入`1`是最小的正整数。 该算法读取最后的数字`1`，发现它不在`02468`，并打印`NO`。 没有尝试除以零或枚举较小的候选者，因此直接处理边界。 

输入`2`是应该产生的最小正整数`YES`。 它唯一的数字是`2`，它是偶数，所以算法打印`YES`。 这证实了单位数字输入不会导致索引问题。 

输入`10`练习看起来特别的最后一个数字`0`。 最终的角色是`0`，属于偶数位集合，所以输出为`YES`。 意外测试仅针对`2`,`4`,`6`， 和`8`会在这里失败。 

对于较大的值，例如`123456789012345678901234567890`，算法忽略除最后一个数字之外的每个数字`0`和打印`YES`。 这说明了为什么该解决方案不需要将数字转换为本机整数或执行与其值成比例的算术。 整除性的决定完全由个位数决定。
