 ## 解决方案
 ## 问题陈述

 工程项目有目标高度`n`和一个宽容`k`。 当项目的实际高度在以下范围内时，项目就被接受`k`目标的单位，包括两个端点。 

任务只是确定最小可接受高度和最大可接受高度。 

## 输入

 输入包含两个正整数。 第一个是目标高度`n`，第二个是允许的公差`k`。 它们在不同的行中给出。 

## 输出

 在第一行打印可接受的下限高度，在第二行打印可接受的上限高度。 

## 问题理解

 可接受的间隔集中在`n`。 向下移动完整公差给出最小允许高度，而向上移动相同量给出最大允许高度。 因此，我们需要的两个值就是`n - k`和`n + k`。 

官方声明没有给出上限`n`或者`k`，只是它们是正整数。 时间限制为 1 秒，内存限制为 256 MB。 由于该解决方案仅需要两次算术运算和两个输出，因此无论输入值有多大，其运行时间都是恒定的。 没有理由使用循环、数组、图形算法或任何其他数据结构。 

第一种边缘情况是公差为零时。 例如，```
5
0
```产生```
5
5
```假设下限和上限必须不同的粗心解决方案是错误的，因为零容差意味着只有目标高度是可接受的。 

第二种边缘情况是当公差大于目标时。 例如，```
2
5
```产生```
-3
7
```下端点可以是负数，因为该语句要求`n - k`直接计算，并且不施加计算下限必须为正的限制。 将答案限制为零的实现会默默地改变所需的间隔。 

第三种边缘情况是当`n`和`k`是平等的。 例如，```
8
8
```产生```
0
16
```下端点恰好为零，因此使用严格不等式而不是包含区间的实现会错误地处理该边界。 

## 方法

 蛮力方法可以生成每个可接受的高度`n - k`通过`n + k`，然后记住第一个和最后一个生成的值。 这是正确的，因为可接受的高度形成一个连续的包含区间。 然而，它的表现完全`2k + 1`迭代。 如果`k`非常大，这意味着即使可以立即获取请求的端点，也意味着不必要的工作量。 

暴力破解之所以有效，是因为可接受的集合是一个区间，但它无法利用仅需要其两个端点的事实。 关键的观察结果是下端点恰好是`k`以下`n`，上端点恰好是`k`多于`n`。 无需检查中间高度。 

这将整个问题简化为两个算术表达式，`n - k`和`n + k`，然后打印它们。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(k) | O(1) | O(1) | 不必要且可能太慢 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取目标高度`n`和宽容`k`。 将两个值分开可以使端点公式直接。 
2. 计算下限为`n - k`。 这是低于目标的最远可接受高度。 
3. 计算上限为`n + k`。 这是距离目标最远的可接受高度。 
4. 打印下限，然后打印上限，每行各占一行，与所需的输出顺序匹配。 

### 为什么它有效

 公差的定义表明每个可接受的高度都在`n - k`和`n + k`，包含在内。 这个区间内最小的数正好是`n - k`，最大的数正好是`n + k`。 由于算法直接输出这两个值，因此两个所需的端点都是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    k = int(input())

    print(n - k)
    print(n + k)

if __name__ == "__main__":
    solve()
```前两行从各自的输入行读取目标高度和公差。 Python 整数在这里适用，因为该语句没有对值强加固定的上限。 

这两个算术表达式直接实现步骤 2 和 3 中的端点计算。 没有循环，因为中间可接受的高度不会影响答案。 

两人`print`调用有意保留所需的顺序。 下端点必须首先出现，然后是上端点。 不存在索引或边界问题，因为间隔端点是直接获得的，而不是通过迭代获得的。

 | 读取输入| 5 | 2 | | |

 | 输出| 5 | 2 | 3 | 7 |

 目标是 5，向任一方向移动两个单位给出从 3 到 7 的间隔。该算法准确地生成这两个端点。 

### 示例 2

 输入是`n = 7`和`k = 3`。 

| 步骤|`n`|`k`| 降低`n-k`| 上`n+k`|
 | ---| ---| ---| ---| ---|
 | 读取输入| 7 | 3 | | |
 | 计算端点 | 7 | 3 | 4 | 10 | 10
 | 输出| 7 | 3 | 4 | 10 | 10

 这里的目标是 7，因此向下 3 个单位给出 4，向上 3 个单位给出 10。这也表明该区间是包容性的，因此两个计算的端点都属于可接受的范围。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(1) | O(1) | 仅执行两次算术运算和两次输出运算。 |

## 测试用例

 官方声明提供了三个示例，如下所示。 自定义测试涵盖零容差、零下端点、负下端点、相等目标和容差以及大整数值。 由于原始语句未指定数字上限，因此无法根据规定的约束构造文字最大大小输入。```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    n = int(input())
    k = int(input())
    print(n - k)
    print(n + k)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# provided samples
assert run("5\n2\n") == "3\n7\n", "sample 1"
assert run("7\n3\n") == "4\n10\n", "sample 2"
assert run("8\n4\n") == "4\n12\n", "sample 3"

# custom cases

assert run("5\n5\n") == "0\n10\n", "lower endpoint exactly zero"
assert run("2\n5\n") == "-3\n7\n", "negative lower endpoint"
assert run("8\n8\n") == "0\n16\n", "target equals tolerance"
assert run("1000000000000000000\n999999999999999999\n") == "1\n1999999999999999999\n", "large integers"

 ## 边缘情况

 当`k = 0`，确切的输入是```
5
0
```该算法计算`5 - 0 = 5`和`5 + 0 = 5`，所以输出是```
5
5
```即使区间仅包含一个整数，两个存储值是容差区间的精确端点这一不变式仍然成立。 

当容差大于目标时，精确输入为```
2
5
```该算法首先计算`2 - 5 = -3`， 然后`2 + 5 = 7`，生产```
-3
7
```端点定义中没有任何内容要求较低的结果保持为正。 该算术必须在没有人工的情况下执行`max(0, ...)`。 

当目标等于容差时，精确输入为```
8
8
```下端点是`8 - 8 = 0`，而上端点是`8 + 8 = 16`。 输出是```
0
16
```这锻炼了负结果和非负结果之间的精确界限，并确认执行减法时没有进行差一调整。 

当输入值非常大时，算法仍然执行完全相同的两个操作。 例如，```
1000000000000000000
999999999999999999
```给出```
1
1999999999999999999
```Python 的整数类型处理这些值时不会出现固定宽度溢出，并且该算法不会分配与任一数字成比例的内存。
