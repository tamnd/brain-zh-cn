 ## 解决方案
 ## 问题理解

 我们在坐标平面中给出了三条不平行的线。 每行写为`y = mx + b`，所以每条线都完全由其斜率描述`m`和 y 轴截距`b`。 每对直线都恰好相交于一个点。 这三个成对的交点形成一个三角形，我们需要将其面积输出为十进制数。 

输入恰好包含三个方程，因此没有参数随输入而增长。 时间限制为 1 秒，内存限制为 256 MB，但这个问题已经是恒定大小的：无论方程中的数值如何，我们只执行 3 条线相交和 1 次三角形面积计算。 

语句中的数值没有明确的界限，因此实现应该使用浮点运算而不是整数运算。 蟒蛇的`float`就足够了，因为法官接受的答案在较小的数字容差范围内。 

一个微妙的情况是所有三条线都经过同一点。 例如，```
y = x + 5
y = 2x + 5
y = 3x + 5
```所有三个交叉点都是`(0, 5)`，所以正确的面积是`0.0`。 粗心的实现可能会假设三条不平行的线总是形成一个非退化三角形，并且无法处理零面积。 

另一个边缘情况是负斜率和负截距。 例如，```
y = -2x - 3
y = x + 1
y = 4x - 8
```符号是等式的一部分，解析时不能丢失。 将输入拆分为空格是很脆弱的，因为该语句描述的是数学方程而不是固定的标记格式。 首先删除空格使两者`y = -2x - 3`和`y=-2x-3`相等的。 

第三种情况是坐标为分数的交点。 例如，```
y = 2x + 3
y = -2x + 9
y = x - 2
```产生非整数交点坐标和面积`28.166666666666664`。 使用整数除法会默默地破坏计算。 

## 方法

 最直接的方法是显式构造三个顶点。 对于每对直线，求解两个线性方程以获得它们的交点。 然后应用三角形面积的标准行列式公式。 

这种方法已经是常数时间了。 正好有三对线，即`(1, 2)`,`(1, 3)`， 和`(2, 3)`。 每个交点都需要进行固定次数的算术运算，然后进行固定大小的鞋带计算。 用数学术语来说，最坏的情况恰好是 3 次交集计算和 1 次面积计算，在计算最终行列式运算之前，对三个坐标对进行大约 21 次基本算术运算。 不存在可能变慢的依赖于输入的循环。 

因此，对于这个问题来说，缓慢的暴力破解和渐近更快的解决方案之间的通常区别并不存在。 有用的优化是代数的而不是渐近的。 我们没有搜索可能的点或使用几何构造，而是使用每条线已经具有形式的事实`y = mx + b`，它立即给出与另一条线的交点。 

对于线路`y = m1 x + b1`和`y = m2 x + b2`,

 他们的交集满足`m1 x + b1 = m2 x + b2`。 

重新排列给出`x = (b2 - b1) / (m1 - m2)`。 

一次`x`已知，将其代入任一行即可得到`y`。 该语句保证没有两条线平行，因此`m1 - m2`永远不会为零。 

然后我们可以使用三个交点`(x1, y1)`,`(x2, y2)`， 和`(x3, y3)`在行列式中`area = |x1(y2-y3) + x2(y3-y1) + x3(y1-y2)| / 2`。 

结果是恒定的时间和恒定的额外空间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 显式交叉+鞋带| O(1) | O(1) | O(1) | O(1) | 已接受 |
 | 直接代数几何| O(1) | O(1) | O(1) | O(1) | 已接受 |

 这两种方法具有相同的渐近复杂度，因为输入始终包含恰好三行。 第二种演示更可取，因为它直接揭示了数学结构并避免了任何不必要的几何机制。 

## 算法演练

 1. 阅读三个方程并将每个方程转换为一对`(m, b)`。 首先删除空格使解析器独立于输入是否包含空格`=`,`x`，以及标志。 
2. 对于每对线`(i, j)`，使用计算它们的交集`x = (bj - bi) / (mi - mj)`。 

分母非零，因为该问题保证没有两条线平行。 
3. 计算相应的 y 坐标`y = mi * x + bi`。 

使用该对的第一条线就足够了，因为该点位于两条线上。 
4. 存储三个交点。 这对`(0, 1)`给出第一个顶点，`(0, 2)`给出第二个，并且`(1, 2)`给出第三个。 
5. 将鞋带公式应用于这三个点，并将绝对值除以二。 取绝对值可处理顶点的顺时针或逆时针排序。 
6. 打印生成的浮点值。 法官接受较小的数字错误，因此无需强制使用特定的十进制表示形式。 

为什么有效：交集公式是直接从一对直线的两个方程获得的，因此每个生成的点正是所需的两两交集。 该算法生成所有三个成对交集，它们正是问题定义的顶点。 鞋带公式给出了由这三个点确定的三角形的精确面积，当三条线重叠时，包括零。 因此最终的值就是所需的三角形面积。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def parse_line(line):
    s = line.replace(" ", "")
    left, right = s.split("x")
    m = float(left.split("=")[1])
    b = float(right)
    return m, b

def intersection(a, b):
    m1, b1 = a
    m2, b2 = b

    x = (b2 - b1) / (m1 - m2)
    y = m1 * x + b1
    return x, y

def solve():
    lines = [parse_line(input().strip()) for _ in range(3)]

    p1 = intersection(lines[0], lines[1])
    p2 = intersection(lines[0], lines[2])
    p3 = intersection(lines[1], lines[2])

    x1, y1 = p1
    x2, y2 = p2
    x3, y3 = p3

    area = abs(
        x1 * (y2 - y3)
        + x2 * (y3 - y1)
        + x3 * (y1 - y2)
    ) / 2.0

    print(area)

if __name__ == "__main__":
    solve()
```解析器首先删除方程中的每个空格。 之后，方程如`y = -2x + 9`变成`y=-2x+9`。 分裂于`x`将斜率部分与截距部分分开，并且`float`处理正值、负值以及小数值。 

这`intersection`函数实现算法演练中导出的方程。 分母使用`m1 - m2`，因此除以零的唯一可能性是两个相等的斜率，该问题明确排除了这一点。 

这三个调用仅使用每个可能的对一次。 它们的顺序对于该区域并不重要，因为鞋带表达式被包裹在`abs`。 

Python 整数不会产生溢出问题，但这里的计算使用`float`因为交叉点坐标和最终面积可能是分数。 打印之前不执行舍入，符合问题的浮点输出要求。

 ### 示例 1

 输入是```
y = 2x + 3
y = -2x + 9
y = x - 2
```关键状态是：

 | 配对| x 的计算 | 交叉口|
 | ---| ---| ---|

 在鞋带公式中使用这三个顶点可以得出`28.166666666666664`。 

此示例练习分数相交坐标。 每个除法必须保持浮点，否则第三个交集将被损坏。

 输入是```
y = 2x + 3
y = -2x + 9
y = -x - 27
```交叉点是：

 | 配对| x| y |
 | ---| ---| ---|

## 边缘情况

 对于并发线路，请考虑```
y = x + 5
y = 2x + 5
y = 3x + 5
```第一条线和第二条线相交于`(0, 5)`。 第一行和第三行也相交于`(0, 5)`，第二行和第三行也做同样的事情。 三个存储的点是相同的，因此鞋带行列式中的每一项都取消，并且算法打印`0.0`。 不需要专门的分支。 

对于负系数，考虑```
y = -2x - 3
y = x + 1
y = 4x - 8
```前两条线相交于`(-4/3, 5/3)`，第一个和第三个相交于`(-1/2, -2)`，第二个和第三个相交于`(9/5, 14/5)`。 结果面积为`6.25`。 解析器保留两个负号，因为在提取斜率和截距之前整个方程已转换为紧凑形式。 

对于分数相交，第一个样本已经提供了相关案例。 第二条线和第三条线的交点是`(11/3, 5/3)`。 浮点实现可以很好地保留这些分数以满足法官的容忍度，而整数除法会将它们变成不正确的整数。 

对于零斜率，考虑```
y = 1000x + 1
y = -1000x + 1
y = 0x - 1000000
```第三条线是水平的，这是完全有效的，因为只禁止平行对。 前两条线相交于`(0, 1)`，而另外两个交点有 x 坐标`-1000.001`和`1000.001`。 结果面积为`1000002000.001`，证明当其中一条线是水平的并且三角形非常大时，该公式也适用。
