 ## 解决方案
 ## 问题理解

 该问题要求两个正整数的最小公倍数（LCM）`a`和`b`。 LCM 是可被两个数字整除的最小正整数。 例如，LCM`2`和`4`是`4`， 因为`4`可以被两者整除，并且没有更小的正整数具有该属性。 

输入包含两个正整数`a`和`b`。 输出是它们的 LCM 作为单个整数。 官方声明并没有给出明确的数值上限`a`和`b`，但预期的解决方案使用 GCD 的欧几里得算法，其运行时间是输入值的对数。 即使整数远大于示例中所示的小值，这也使其适用。 扫描可能的倍数或重复测试整除性的解决方案可能需要与答案本身成比例的大量操作，而答案可能比输入大小大得多。 

在一些小情况下，基于简单公式的实现可能会出错。 如果一个数字已经整除另一个数字，则 LCM 是较大的数字。 用于输入`2 4`，正确的输出是`4`。 一种从以下位置开始搜索的方法`a * b`不减少公因数会浪费工作，而意外地仅搜索两者的严格倍数的实现可能会错过答案。 

当数字相等时，LCM 就是相同的数字。 用于输入`7 7`，正确的输出是`7`。 基于生成倍数的粗心实现可能会不必要地搜索第二次出现，而不是认识到第一个数字已经是公倍数。 

这些数字也可以是互质的。 用于输入`3 5`，正确的输出是`15`。 在这种情况下，GCD 是`1`，因此没有可以从产品中删除的公因子。 假设总是存在非平凡的 GCD 的实现会产生不正确的结果。 

两个输入的顺序无关紧要。 为了`4 6`和`6 4`，LCM 为`12`在这两种情况下。 欧几里得算法可以自然地处理任一排序，因此无需在计算 GCD 之前手动交换输入。 

## 方法

 一种直接的方法是搜索倍数，直到找到一个可以被两个数字整除的数字。 我们可以从较大的开始`a`和`b`，测试它是否可以被两者整除，然后继续下一个整数，直到找到公倍数。 这是正确的，因为遇到的第一个公倍数正是 LCM。 然而，在最坏的情况下，搜索可能需要 θ(LCM(a, b)) 整除性检查。 对于互质数，最小公倍数是`a * b`，因此最坏的情况可能需要 θ(`a * b`） 运营。 即使对于中等大的输入，这也是不切实际的。 

另一种直接的数学方法是对两个数字进行因式分解，并根据它们的质因数构建 LCM。 这是可行的，但保理需要的工作量远远多于必要的工作量。 这个问题已经给了我们GCD和LCM之间的关键关系：`LCM(a, b) = a * b / GCD(a, b)`。 

剩下的任务是有效地计算 GCD。 

欧几里得算法正是提供了这一点。 对于正整数，替换`(a, b)`和`(b, a mod b)`保留他们的 GCD。 重复应用此变换会使第二个值变小，直到变为零。 此时，第一个值是 GCD。 迭代次数在较小的输入中是对数的。 

LCM 公式的实现也有一个小的改进。 而不是计算`a * b // gcd(a, b)`，我们可以计算`a // gcd(a, b) * b`。 从数学上讲，它们是相同的，但首先除法使中间值更小。 Python 整数不会溢出，但这仍然是常规形式，并直接传输到固定宽度语言，例如 C++。 

蛮力方法之所以有效，是因为它显式搜索第一个公倍数，但会失败，因为搜索空间可能很大。 LCM 由 GCD 决定的观察结果让我们用欧几里得算法代替整个搜索。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(LCM(a, b)) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(log min(a, b)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取两个正整数`a`和`b`。 它们的顺序并不重要，因为 GCD 和 LCM 都是对称的。 
2. 计算`g = gcd(a, b)`使用欧几里得算法。 尽管`b`不为零，则替换`(a, b)`和`(b, a % b)`。 什么时候`b`达到零时，剩余值`a`是GCD。 

这种变换有效的原因是每个公约数`a`和`b`也分`a % b`，以及每个公约数`b`和`a % b`也分`a`。 因此，公约数集不会改变。 
3.概念上恢复原值并计算`a // g * b`。 将一个输入除以 GCD 会准确地删除两个数字已经共享的因子，因此乘以另一个输入会产生包含所有所需因子的最小数字。 
4. 打印生成的 LCM。 由于两个输入都是正数，因此结果也是正数。 

### 为什么它有效

 让`g = gcd(a, b)`。 我们可以写`a = g * x`和`b = g * y`， 在哪里`x`和`y`没有公因数。 的任意公倍数`a`和`b`必须包含共享因子`g`，而这两个数字所需的其余因子由下式表示`x`和`y`。 自从`x`和`y`是互质的，包含两者的最小数是`g * x * y`，等于`a * b / g`。 欧几里德算法正是计算出这个`g`，所以最终的公式总是产生 LCM。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

def solve():
    a, b = map(int, input().split())

    g = gcd(a, b)
    lcm = (a // g) * b

    print(lcm)

if __name__ == "__main__":
    solve()
```这`gcd`函数是欧几里得算法的迭代形式。 每次迭代都会将该对替换为`(b, a % b)`，余数严格小于`b`，因此循环必须终止。 

循环结束后，`a`包含GCD。 原始输入值仍然可用，因为函数参数是局部的`gcd`，因此可以立即计算 LCM。 

表达式`(a // g) * b`优于`a * b // g`。 两者给出相同的数学结果，但在乘法之前除法可以避免不必要的大中间值。 Python 具有任意精度的整数，因此在此实现中不存在整数溢出问题。 

欧几里德算法中不存在相差一的条件。 当第二个值非零时，循环将继续进行。 当它变为零时，第一个值是算法定义的 GCD。 

## 工作示例

 ### 示例 1

 输入是：```
2 4
```欧几里得算法和最终计算过程如下。 

| 步骤|`a`|`b`| 运营|
 | --- | --- | --- | --- |
 | 开始 | 2 | 4 | 开始 GCD |
 | 1 | 4 | 2 |`(2, 4)`变成`(4, 2)`|
 | 2 | 2 | 0 |`(4, 2)`变成`(2, 0)`|
 | 完成 | 2 | 0 | GCD = 2 |

 现在`g = 2`，所以LCM是`(2 // 2) * 4 = 4`。 

GCD 删除了两个输入已经共享的因子，仅留下最小公倍数所需的因子。

 输入是：```
1101 1816
```欧几里得算法给出：

 | 步骤|`a`|`b`| 剩余|
 | --- | --- | --- | --- |
 | 开始 | 1101 | 1101 1816 |`1101`|
 | 1 | 1816 | 1101 | 1101`715`|
 | 2 | 1101 | 1101 715 | 715`386`|
 | 3 | 715 | 715 386 | 386`329`|
 | 4 | 386 | 386 329 | 329`57`|
 | 5 | 329 | 329 57 | 57`44`|
 | 6 | 57 | 57 44 | 44`13`|
 | 7 | 44 | 44 13 |`5`|
 | 8 | 13 | 5 |`3`|
 | 9 | 5 | 3 |`2`|
 | 10 | 10 3 | 2 |`1`|

 最大公约数是`1`，所以这两个数是互质的。 因此 LCM 是他们的产品：`1101 * 1816 = 1999416`。 

该轨迹表明，无论哪个输入最初较大，欧几里得算法都有效。 第一次迭代只是将较大的值交换到第一个位置，作为正常的一部分`(b, a % b)`转变。

import sys
import io

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

def solve():
    a, b = map(int, input().split())
    g = gcd(a, b)
    print((a // g) * b)

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    try:
        sys.stdin = io.StringIO(inp)
        input = sys.stdin.readline

        old_stdout = sys.stdout
        sys.stdout = io.StringIO()

        try:
            solve()
            return sys.stdout.getvalue()
        finally:
            sys.stdout = old_stdout
    finally:
        sys.stdin = old_stdin
        input = old_input

# Provided samples

# Equal values

 ## 边缘情况

 对于相同的输入，请考虑：```
7 7
```欧几里得第一步发生变化`(7, 7)`到`(7, 0)`，所以 GCD 是`7`。 最终计算结果为`(7 // 7) * 7 = 7`。 输出是：```
7
```基于搜索的实现可能会执行不必​​要的工作，但基于 GCD 的方法会立即完成。 

对于一个数字整除另一个数字的情况，请考虑：```
2 4
```最大公约数是`2`，LCM 为`(2 // 2) * 4 = 4`。 输出是：```
4
```该算法不需要将整除性视为特殊情况。 它自然地脱离了 GCD 公式。 

对于互质数，请考虑：```
3 5
```欧几里得算法产生的 GCD 为`1`。 因此，LCM 是`(3 // 1) * 5 = 15`，给予：```
15
```这会检查无法从产品中删除任何公因数的情况。 

对于一对大的互质数，请考虑：```
999999937 1000000000
```他们的GCD是`1`，所以结果是：```
999999937000000000
```在达到这个公倍数之前，强力搜索必须检查大量候选者。 相反，欧几里得算法仅在对数次模运算后完成，这是最佳解决方案具有良好扩展性的核心原因。
