 ## 解决方案
 ## 问题理解

 任务是测量固定圆形色轮上的距离。 色轮包含七种颜色，顺序如下：`red -> orange -> yellow -> green -> blue-green -> blue -> purple -> red`对于每个测试用例，我们收到两个颜色名称。 我们需要沿着轮盘从第一种颜色到第二种颜色所需的最短移动次数。 从一种颜色移动到其相邻颜色需要花费 1 美元，并且由于轮子是圆形的，因此我们可以朝任一方向行驶。 第一个颜色不计算在内，而目标颜色则计算在内，因此答案正是较短路径中的边数。 

官方声明给出了 1 秒和 256 MB，并指定每个查询包含来自轮盘的两个颜色名称。 可能的颜色数量固定为七种，因此一个测试用例的实际计算时间为常数时间。 即使测试用例的数量非常大，O(n) 解决方案也足够了，因为每个用例只需要少量操作。 

主要的边缘情况来自轮子的圆形性质。 如果两种颜色相等，则距离为零。 例如，```
1
green green
```有输出```
0
```总是计算至少一步的粗心实现可能会错误地打印`1`。 

另一个常见的错误是忘记了轮子是环绕的。 例如，```
1
purple orange
```有输出```
2
```因为较短的路线是`purple -> red -> orange`。 将颜色视为普通线性数组将给出距离 5。 

第三种边界情况是相邻对`blue`和`blue-green`:```
1
blue blue-green
```正确的输出是```
1
```两种颜色在轮盘上是连续的，因此它们的距离为一。 意外计算两个端点的实现将产生两个端点。 

## 方法

 最直接的解决方案是将七种颜色按轮顺序存储并按顺序进行搜索。 给定两种颜色，我们找到它们的位置并模拟围绕方向盘的运动。 由于只有七种颜色，即使是字面上的强力模拟也只能执行恒定数量的操作。 七色轮上最长的可能最短路径是三个边缘，尽管扫描整个色轮的不太仔细的实现仍然每个查询最多执行七个位置检查。 不存在会变得太慢的实际输入大小。 

有用的观察是轮子永远不会改变，因此每种颜色都可以分配一个固定的整数位置。 一次`red`是位置`0`,`orange`是`1`，依此类推，问题就变成了一个周期上两个位置之间的距离。 

假设位置是`a`和`b`。 直接穿过数组移动的距离为`abs(a - b)`。 另一个方向环绕轮子的末端并有距离`7 - abs(a - b)`。 答案是这两个值中较小的一个。 

由于状态空间只有七种颜色，暴力模拟和位置公式都是正确的。 公式更可取，因为它直接表达了结构，并将每个查询简化为字典查找、减法和最小运算。

 | --- | --- | --- | --- |
 | 车轮模拟| 总体 O(n)，每个测试用例 O(1) | O(1) | O(1) | 已接受 |
 | 持仓公式| 总体 O(n)，每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将颜色按轮顺序存储为`red, orange, yellow, green, blue-green, blue, purple`。 为每种颜色分配其索引`0`通过`6`。 
2.读取当前测试用例的两种颜色并查找它们的索引`a`和`b`。 索引准确地保留了色轮描述的邻接关系。 
3. 计算`direct = abs(a - b)`。 这是通过数组的正常顺序时的距离。 
4. 计算`wrap = 7 - direct`。 这表示绕圆轮沿相反方向行驶。 如果直接路径从数组的一端穿过到另一端，则这些正是路径使用的边。 
5. 打印`min(direct, wrap)`。 这两个值代表围绕一个周期仅有的两个方向，因此较小的值是最短的距离。 

为什么有效：为七种颜色分配位置后，循环中从一种颜色到另一种颜色的每条路径都是顺时针或逆时针的。 它们的长度是`abs(a-b)`和`7-abs(a-b)`。 该算法采用这两条完整路径中较小的一条，因此它始终返回最短距离。 当两种颜色相等时，`direct`为零，答案正确为零。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

ORDER = {
    "red": 0,
    "orange": 1,
    "yellow": 2,
    "green": 3,
    "blue-green": 4,
    "blue": 5,
    "purple": 6,
}

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        first, second = input().split()

        a = ORDER[first]
        b = ORDER[second]

        direct = abs(a - b)
        wrap = 7 - direct

        out.append(str(min(direct, wrap)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```这`ORDER`字典是色轮的中心表示。 使用显式索引可以避免对字符串排序的任何依赖，这将是不正确的，因为字母顺序与轮子无关。 

对于每个查询，两个字符串都会转换为整数位置。 绝对差给出了没有环绕的距离。 例如，`purple`有地位`6`和`orange`有地位`1`，所以直接距离是`5`。 

相反的方向有长度`7 - 5 = 2`，对应于`purple -> red -> orange`。 取最小值即可得到所需的最短距离。 

Python 中不存在整数溢出问题，最大中间值只有 7。 输入逐行处理，输出累积并写入一次，这是一种简单的快速 I/O 模式，即使测试用例数量很大也适用。

 ## 边缘情况

 对于相同的颜色，请考虑：```
1
blue blue
```两种颜色都映射到索引`5`， 所以`direct = abs(5 - 5) = 0`。 环绕距离为`7`，且最小值为零。 该算法打印：```
0
```零直接距离是正确的解释，因为不需要移动即可从自身到达颜色。 

对于环绕对，请考虑：```
1
purple red
```

`purple`有索引`6`和`red`有索引`0`。 直接距离是`6`，但圆周距离是`7 - 6 = 1`。 该算法打印：```
1
```这对应于相邻的边`purple`回到`red`。 仅计算的线性阵列解决方案`abs(a-b)`会错误地返回`6`。 

对于靠近周期另一侧的一对，请考虑：```
1
purple orange
```职位是`6`和`1`，给出直接距离`5`和环绕距离`2`。 答案是：```
2
```路径是`purple -> red -> orange`。 这是必须将问题视为循环而不是正常序列的关键原因。 

最后，考虑最大可能的最短距离：```
1
red green
```职位是`0`和`3`，所以两条相关路线都有长度`3`和`4`。 最小值是`3`，生产：```
3
```在七节点循环上，任何颜色对的最短距离都不能大于三。 这为任何实现提供了有用的健全性检查：每个有效答案必须位于零和三之间。
