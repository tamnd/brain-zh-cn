 ## 解决方案
 ## 问题理解

 该问题将心率测量结果分为五个健身区之一。 学生的最大心率，缩写为 MHR，定义为 (220-\text{age})。 然后将每个记录的心率与 MHR 进行比较。 

区域 5 包含 MHR 90% 到 100% 的读数。 区域 4 包含从 80% 到（但不包括）90% 的读数。 区域 3 覆盖 70% 到小于 80%，区域 2 覆盖 60% 到小于 70%，低于 60% 的任何区域都属于区域 1。任务是为每个记录的心率打印相应的区域。 官方的问题指定输入为一个年龄，然后是读数的数量，然后是这些读数。 

不需要复杂的数据结构，因为每个心率值都独立于其他值。 如果有 (n) 个读数，我们必须检查所有 (n) 个读数，给出 (O(n)) 的自然下限。 重复比较每对读数的算法将不必要地需要 (O(n^2)) 工作，并且随着测量数量的增加而变得不合适。 

主要的数值边缘情况是心率恰好位于区域边界上。 例如，20 岁时，MHR 为 200，因此读数 180 正好是 90%，必须打印为区域 5，而不是区域 4。另一个边界出现在 160，正好是 80%，属于区域 4。同样的区别也适用于 140 和 120。 

例如，输入```
20
4
180
160
140
119
```产生```
Zone 5
Zone 4
Zone 3
Zone 1
```粗心的浮点实现也会使边界处理变得不必要的脆弱。 比较 (r \ge 90%\cdot MHR) 可以重写为 (10r \ge 9MHR)，因此每个决定都可以通过精确的整数运算来做出。 

第二种边缘情况是读数低于 60%。 对于 20 岁、MHR 200 的情况，读数 119 是 59.5%，因此属于区域 1。检查整数百分比是否至少为 60 在这里是等效的，但计算精确的叉乘比较更安全，并且直接代表规定的百分比边界。 

## 方法

 最直接的方法是计算一次学生的 MHR，然后独立处理每个心率测量结果。 对于每个读数，我们可以计算其 MHR 百分比，并将其与 90、80、70 和 60 进行比较。这是正确的，因为这些区域仅由这些阈值定义，并且测量之间没有交互作用。 其最坏情况下的工作与读数数量成正比，每个读数的算术和比较量恒定。 

稍微好一点的实现完全避免了浮点运算。 假设测得的心率为(r)，MHR 为(M)。 不用测试 (r/M \ge 0.9)，而是将两边乘以 (10M)，得到 (10r \ge 9M)。 相同的变换给出其他边界为 (10r \ge 8M)、(10r \ge 7M) 和 (10r \ge 6M)。 

强力数值计算之所以有效，是因为每次测量都是独立的，但浮点百分比增加了精度问题，但没有提供任何好处。 每个阈值都是一个简单的有理百分比的观察结果让我们可以用整数乘法替换所有除法。 生成的算法仍然是线性的，但其比较是精确的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 浮点分类| O(n) | 除了输入存储之外，O(1) | 已接受 |
 | 整数阈值比较 | O(n) | 除了输入存储之外，O(1) | 已接受 |

 ## 算法演练

 1.读取学生的年龄并计算`mhr = 220 - age`。 MHR 对于整个输入来说是固定的，因此计算一次就可以避免对每次测量重复相同的操作。 
2. 读取心率测量次数。 我们独立处理每个测量结果，因为一个读数的分类不会影响另一个读数。 
3. 阅读`r`,第一次测试`10 * r >= 9 * mhr`。 这正是 MHR 的条件 (r \ge 90%)，因此满足它会将读数置于区域 5。 
4. 如果 5 区条件失败，则测试`10 * r >= 8 * mhr`。 达到 80% 但未达到 90% 的值属于区域 4。 
5. 继续使用 70% 和 60% 阈值。 满足的第一个阈值决定了区域，因为检查是从最高百分比向下执行的。 
6. 如果四个阈值均不满足，则读数低于 MHR 的 60%，属于 1 区。 

为什么有效：对于每次读取，算法都会准确检查划分五个区域的四个边界。 第一次成功的比较确定了最高的适用边界，因此读数恰好落入相应的区间。 整数叉乘相当于原来的百分比比较，因此不会改变任何分类。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    age = int(input())
    n = int(input())

    mhr = 220 - age

    ans = []

    for _ in range(n):
        r = int(input())
        x = 10 * r

        if x >= 9 * mhr:
            ans.append("Zone 5")
        elif x >= 8 * mhr:
            ans.append("Zone 4")
        elif x >= 7 * mhr:
            ans.append("Zone 3")
        elif x >= 6 * mhr:
            ans.append("Zone 2")
        else:
            ans.append("Zone 1")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```前两个输入操作读取学生的年龄和测量次数。 价值`mhr`计算一次，因为每次读数都是相同的。 

对于每个心率，`x = 10 * r`让程序与 MHR 的整数倍进行比较。 例如，区域 5 的条件是`10 * r >= 9 * mhr`，在数学上等同于 (r \ge 0.9MHR)。 

这`elif`订购是经过深思熟虑的。 正好 90% 的读数满足 90% 和 80% 比较，但它必须是区域 5，因此必须首先检查最高阈值。 同样的推理也适用于所有其他边界。 

Python 整数具有任意精度，因此乘法不会溢出。 对于这个问题的输入范围，即使是固定宽度的 64 位整数也足够了，但 Python 的整数行为使实现变得简单。 

最后将结果累加并写在一起。 这避免了为每个读数执行单独的输出操作。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个心率测量值都会被处理一次，并进行恒定数量的比较。 |
 | 空间| O(n) | 该实现在打印输出字符串之前存储它们。 |

 线性运行时间是最佳的，因为程序必须至少检查每个测量一次。 每次读数的数值工作是恒定的，并且与输入大小相比，整数计算量很小。 如果立即打印输出而不是累积输出，则辅助空间可以减少到 (O(1))，尽管提交的实现使用输出列表来提高 I/O 效率。

 ## 边缘情况

 对于 90% 边界，考虑年龄 20 且心率为 180。MHR 为 200，并且 (180/200=90%)。 第一次比较变成 (10\cdot180=1800) 和 (9\cdot200=1800)，因此条件为真，程序打印`Zone 5`。 粗心的实现使用`>`而不是`>=`会错误地将此读数归类为区域 4。 

对于紧邻边界以下的值，考虑相同的年龄和 179 的心率。该值是 MHR 的 89.5%。 区域 5 比较失败，因为 (1790<1800)，而区域 4 比较成功，因为 (1790\ge1600)。 正确的输出是`Zone 4`。 

对于 60% 边界，20 岁时的 MHR 为 200，120 正好是 60%。 比较 (10\cdot120\ge6\cdot200) 变为 (1200\ge1200)，因此正确的输出是`Zone 2`。 严格的`>`比较会错误地将该值发送到区域 1。 

对于略低于 60% 的值，请使用相同年龄的 119。 这里 (10\cdot119=1190) 小于 (6\cdot200=1200)，因此区域 2 到区域 5 的条件都不会成功。 算法进入最终阶段`else`和打印`Zone 1`。 

对于重复的相同读数，每个测量值都会独立分类。 如果 20 岁的所有读数均为 120，则每条输出行都是`Zone 2`。 先前测量中的状态不会被带入下一次测量。 

该实现还可以自然地处理 100% 以上的读数。 这样的读数满足 90% 的比较，并被归类为区域 5，这是最高的可用区域。
