 ## 解决方案
 ## 问题理解

 该问题要求树中无序顶点对的数量，其最短路径恰好包含`k`边缘。 输入描述了一个无向树`n`顶点，然后是目标距离`k`。 输出是一个整数，表示有多少个不同的顶点对满足此距离要求。 

一棵树的每对顶点之间都有一条唯一的路径，这是使问题易于处理的属性。 我们不需要重复搜索最短路径，因为任意两个节点之间只有一条可能的路径。 

重要的限制是`n`可以达到50,000，同时`k`最多 500 个。检查每对顶点的算法需要大约`n² / 2`距离计算，最大规模约为 12.5 亿次运算。 这在正常的比赛环境中太慢了。 的小值`k`这表明我们应该避免考虑长距离，而只关注长度可达的路径`k`。 

一些边缘情况可能会破坏简单的实现。 

对于单个顶点树，没有可计数的对。 

输入：```
1 1
```正确的输出是：```
0
```假设至少存在一条边的解决方案在构建邻接列表或初始化递归时可能会失败。 

什么时候`k = 1`，每个有效对只是树的一条边。 例如：```
3 1
1 2
2 3
```正确的输出是：```
2
```仅针对具有更深共同祖先的对设计的方法可能会错过这些直接联系。 

链还可能暴露重复计算错误。 为了：```
5 2
1 2
2 3
3 4
4 5
```正确的输出是：```
3
```有效的对是`(1,3)`,`(2,4)`， 和`(3,5)`。 如果无法避免重复，则独立计算来自两个端点的路径将会对每对进行两次计数。 

## 方法

 直接的解决方案是尝试每对顶点。 对于每一对，我们可以运行广度优先搜索或使用树结构来计算它们的距离，然后如果距离等于则增加答案`k`。 这是正确的，因为每个可能的对都会被检查。 

问题是成本。 大致有`n²`对，即使是简单的恒定时间距离计算在以下情况下仍然太多`n = 50000`。 对于每个顶点的 BFS，复杂度变为`O(n²)`，或更糟，具体取决于实现细节，这远远超出了限制。 

关键的观察是每条长度有效的路径`k`具有独特的中点或中间边缘。 如果我们选择树的质心，则每条路径要么完全位于删除该质心后的一个剩余组件内，要么穿过该质心。 这让我们可以计算所有通过质心的路径，删除较小的子问题，并递归地解决它们。 

对于一个质心，我们只需要知道距它的每个距离处有多少个顶点。 如果一棵子树中的一个顶点是距离`d`从质心开始，然后是远处另一个子树中的顶点`k-d`创建一个有效的对。 我们组合来自不同子树的信息，同时确保我们永远不会在同一质心步骤中对同一子树的两个顶点进行计数。 

暴力方法之所以有效，是因为直接检查每一对，但由于对太多而失败。 质心分解观察将问题简化为更小的树，允许每个顶点仅参与对数数量的分解级别。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 质心分解| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 找到当前树组件的质心。 质心是一个顶点，在删除它之后，每个剩余的连接组件最多具有原始顶点的一半。 这保证了递归分解具有对数深度。 
2. 统计所有经过该质心的有效路径。 从频率数组开始，其中`distance 0`包含质心本身。 对于每个子子树，收集距质心每个距离处存在多少个顶点。 在将该子树的距离添加到全局频率数组之前，查询有多少已处理的顶点处于该距离`k - current_distance`。 这些对是有效的，因为它们来自不同的子树并且它们的路径穿过质心。 
3. 将当前子树的距离添加到频率数组中。 顺序很重要，因为在此质心处理步骤期间，同一子树内的顶点不应配对。 它们的路径不经过质心，并且稍后当该子树成为单独的递归组件时进行处理。 
4. 将质心标记为已删除，并递归求解每个剩余组件。 每个组件都是独立的，因为它内部的每条路径都不能使用删除的质心。 
5. 继续，直到处理完所有组件。 质心处理过程中找到的所有计数的总和就是最终答案。 

为什么它有效：

 每对顶点在分解中恰好有一个最高级别的质心，其中两个顶点被分成不同的组件，或者其中一个是质心本身。 在那一刻，他们的路径穿过该质心并被计算一次。 如果两个顶点仍处于同一组件中，则该对尚未计算在内，但会在更深的分解级别上进行考虑。 由于每个可能的对都在其唯一的分离质心处处理，因此不会丢失或重复任何对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    graph = [[] for _ in range(n)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        graph[a].append(b)
        graph[b].append(a)

    removed = [False] * n
    size = [0] * n
    ans = 0

    def calc_size(v, p):
        size[v] = 1
        for u in graph[v]:
            if u != p and not removed[u]:
                size[v] += calc_size(u, v)
        return size[v]

    def find_centroid(v, p, total):
        for u in graph[v]:
            if u != p and not removed[u]:
                if size[u] > total // 2:
                    return find_centroid(u, v, total)
        return v

    def collect(v, p, d, arr):
        if d > k:
            return
        arr.append(d)
        for u in graph[v]:
            if u != p and not removed[u]:
                collect(u, v, d + 1, arr)

    def decompose(v):
        nonlocal ans

        total = calc_size(v, -1)
        c = find_centroid(v, -1, total)

        freq = [0] * (k + 1)
        freq[0] = 1

        for u in graph[c]:
            if removed[u]:
                continue

            distances = []
            collect(u, c, 1, distances)

            for d in distances:
                if d <= k:
                    ans += freq[k - d]

            for d in distances:
                if d <= k:
                    freq[d] += 1

        removed[c] = True

        for u in graph[c]:
            if not removed[u]:
                decompose(u)

    decompose(0)
    print(ans)

if __name__ == "__main__":
    solve()
```邻接表存储树，因为每个顶点只需要访问其邻居。 这`removed`array 表示已经成为质心的顶点，不应包含在以后的递归组件中。 

第一对函数，`calc_size`和`find_centroid`，定位当前组件的质心。 大小计算会忽略已删除的顶点，因为分解是对每个剩余组件独立执行的。 

这`collect`函数将从质心到一个子子树的距离收集起来。 距离后停止`k`因为更长的路径永远无法得出答案。 

计数阶段使用`freq`作为从距离到已处理顶点数的映射。 当处理新的子树时，查询`freq[k - d]`计算通过质心的总距离恰好为的所有对`k`。 只有在查询之后我们才将子树距离添加到`freq`，防止来自同一子树的对在此级别进行计数。 

Python 整数自动处理大答案大小，这可能接近`n²`。 距离数组有大小`k + 1`，因此大路径中不存在隐藏的内存增长。

 对于第一个样本：```

1 2
2 3
3 4

```质心可以是顶点`2`。

 | --- | --- | --- | --- |

 处理完所有递归组件后，总数变为 4。 该跟踪显示了为什么在插入之前查询子树：来自不同分支的顶点形成通过质心的路径。 

对于第二个样本：```

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n) | O(n log n) | 每个质心层处理其组件中的所有顶点，分解深度是对数的。 |
 | 空间| O(n) | 树、辅助数组和递归堆栈需要线性内存。 |

 约束条件允许`n = 50000`，其中二次对枚举是不可能的。 质心分解使每个分解级别的总功接近线性，并且在所需的限制范围内舒适地拟合。

 ## 边缘情况

 对于仅包含一个顶点的树，质心分解从该顶点开始，仅计算距离为零处的质心本身，并且找不到对。 输入`1 1`正确产生`0`。 

为了`k = 1`，该算法计算相邻顶点对的数量。 由于每条边的距离为 1，因此当其端点在某个质心级别分离时，每条边都会被发现。 输入：```
3 1
1 2
2 3
```通过找到两个有效对并返回来处理`2`。 

对于路径形树：```
5 2
1 2
2 3
3 4
4 5
```该算法永远不会对同一对进行两次计数。 一对如`(1,3)`仅当质心位于它们之间的路径上并将两个顶点分成不同的处理部分时才被计数。 如果它们保持在一起，递归会稍后处理它们。 

该实现还处理以下情况`k`大于树的直径。 所有收集的距离一旦超过就会停止贡献`k`，并且频率查找无法找到匹配的距离，因此答案仍然为零。
