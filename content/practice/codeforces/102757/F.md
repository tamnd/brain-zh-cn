 ## 解决方案
 ## 问题理解

 迷宫是一条只有三行的走廊`n`列。 每个单元格要么是开放的，要么是阻塞的。 Alice 可以从第一列中的任何开放单元格开始，并且可以在开放单元格中向上、向下、向左或向右移动。 目标是确定是否至少有一条可能路径到达最后一列中的任何开放单元格。 输入包含走廊的宽度和描述行的三个二进制字符串，其中`0`代表一个适合步行的位置，并且`1`代表一堵墙。 输出是`Solvable!`如果可以到达最后一列并且`Unsolvable!`否则。 

宽度可达`10^4`，所以迷宫只包含大约`3 * 10^4`细胞。 检查每个细胞恒定次数的解决方案很容易足够快。 对可能路径进行强力搜索是不可能的，因为随着迷宫变大，可能行走的数量呈指数增长。 该约束强烈指向图遍历，其中每个单元格都被处理一次。 

棘手的情况来自于起点不固定。 一个常见的错误是仅从左上角的单元格开始，但 Alice 可以选择第一列中的任何行。 例如：```
2
10
00
10
```正确的输出是：```
Solvable!
```仅从第 0 行开始的搜索将立即失败，因为左上角的单元格被阻塞，即使左中单元格可以到达第二列。 

另一种边缘情况是当目的地附近的单元格打开但与左侧断开连接时。 例如：```
3
011
010
010
```正确的输出是：```
Unsolvable!
```最后一列包含开放单元格，但没有从第一列到这些单元格的路径。 一种粗心的方法，仅检查最后一列是否包含`0`会产生错误的答案。 

最终的边界情况是一个完全开放的迷宫：```
2
00
00
00
```正确的输出是：```
Solvable!
```该路径可以简单地直接穿过任何行。 任何意外需要移动所有三行或尝试找到唯一路径的实现都会在这里失败。 

## 方法

 直接的方法是将每个开放单元视为图顶点。 当两个顶点的单元共享一条边时，它们就被连接起来。 暴力解决方案可以从第一列开始枚举可能的路径，并在到达最后一列时停止。 这是正确的，因为每个有效的移动序列都对应于图中的一条路径。 问题在于可能路径的数量。 具有许多分支点的迷宫可以产生指数数量的选择，因此单独探索路径很快就变得不可行。 

有用的观察是，这个问题只问路径是否存在。 我们不需要路径本身、路径的长度或路径的数量。 一旦某个单元格可到达，到达它的确切方式就不再重要了。 这意味着我们可以将单元格标记为已访问并立即从所有可能的起始位置向外扩展。 

广度优先搜索或深度优先搜索就足够了，因为每个开放单元最多被考虑一次。 三行形状不需要任何特殊的迷宫算法。 它只会减少每个单元可以拥有的可能邻居的数量。 该图具有线性数量的顶点和边，因此标准遍历会在限制内完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 分支数量呈指数增长 | O(n) | 太慢了 |
 | 图遍历 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 创建一个队列，其中包含第一列中的每个打开单元格。 这些都是有效的起始位置，因为 Alice 可以选择任何行。 
2. 反复从队列中删除一个单元并检查其四个可能的邻居。 如果邻居在迷宫内，打开且尚未访问，则将其标记为已访问并将其添加到队列中。 访问过的数组可以防止重复工作和无限的移动循环。 
3. 处理单元格时，检查是否有访问过的单元格属于最后一列。 到达该列的任何行都意味着迷宫有一个解决方案。 
4. 如果队列变空而未到达最后一列，则报告`Unsolvable!`。 每个可到达的位置都已被探索过，因此不存在缺失的路径。 

为什么它有效：遍历保持了以下不变性：每个标记为已访问的单元格都可以从第一列中的某个起始单元格到达。 最初这是正确的，因为仅插入有效的起始单元格。 每当添加新单元格时，都会通过从已可到达的单元格进行有效移动来到达它，因此不变量仍然为真。 搜索将继续进行，直到所有可到达的单元都被耗尽。 如果访问了最后一列，则记录的路径证明迷宫是可解的。 如果从未访问过，则已检查所有可能可达的位置，证明不存在有效路径。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n = int(input())
    maze = [input().strip() for _ in range(3)]

    visited = [[False] * n for _ in range(3)]
    q = deque()

    for r in range(3):
        if maze[r][0] == '0':
            visited[r][0] = True
            q.append((r, 0))

    directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    while q:
        r, c = q.popleft()

        if c == n - 1:
            print("Solvable!")
            return

        for dr, dc in directions:
            nr = r + dr
            nc = c + dc

            if 0 <= nr < 3 and 0 <= nc < n:
                if not visited[nr][nc] and maze[nr][nc] == '0':
                    visited[nr][nc] = True
                    q.append((nr, nc))

    print("Unsolvable!")

if __name__ == "__main__":
    solve()
```因为迷宫高度是固定的，所以输入被读取为三个字符串。 访问过的数组与迷宫具有相同的维度，并记录是否已经发现了某个位置。 

初始化步骤将所有三个可能的单元格插入第一列中。 这是此问题中最常见的实现错误，因为假设只有一个起始位置会改变问题。 

队列存储行和列对。 每次删除一个单元格时，代码都会在探索邻居之前检查它是否在最后一列中。 边界检查防止在三行或行之外建立索引`n`列。 

每个有效邻居在插入之前而不是删除之后被标记。 这可以避免当两条不同的路径到达同一单元时多次添加该单元。

 ## 边缘情况

 对于多启动情况：```
2
10
00
10
```该算法忽略第一行和第三行中被阻塞的单元格，然后仅将中左单元格插入队列中。 从`(1,0)`它移动到`(1,1)`，位于最后一列，所以答案是`Solvable!`。 

对于断开连接的目标情况：```
3
011
010
010
```唯一的起始单元格是`(1,0)`。 由于所有可能的路线都被封锁，因此遍历无法移动到其他任何地方。 最后一列中的单元格从未被标记为已访问，因此算法可以正确打印`Unsolvable!`。 

对于完全开放的迷宫：```
2
00
00
00
```第一列中的所有三个单元格都进入队列。 搜索立即扩展到走廊，到达纵队`1`。 由于到达最后一列的任何行就足够了，算法返回`Solvable!`。
