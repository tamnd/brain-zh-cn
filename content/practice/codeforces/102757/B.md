 ## 解决方案
 # 问题理解

 该问题模拟一家商店，每位顾客用一枚铜币购买一件商品。 顾客并不总是用铜币付款，他们可能会交出银币或金币。 阿方索必须立即归还正确的零钱，然后才能为下一位顾客提供服务。 

钱币系统是二元的：一枚银币与两枚铜币等值，一枚金币与两枚银币等值。 相应地，这些值是青铜 = 1、银 = 2、金 = 4。阿方索开始时没有硬币，因此前几个顾客可以确定他是否有足够的较小硬币来继续。 目标是决定是否可以为整个队列提供服务。 

客户数量可以达到 100000 个，因此重复搜索整个历史记录或尝试可能的选择的算法会太慢。 我们需要对客户进行单次传递，每个客户只需持续工作，从而提供 O(n) 解决方案。 

棘手的情况来自于总资金不够。 阿方索可能有足够的价值，但没有合适的变革面额。 例如：```
3
gold
gold
gold
```正确的输出是：```
NO
```在获得第一枚金币后，阿方索拥有一枚金币，但需要归还三枚铜币。 他没有更小的硬币，所以他立即失败了。 一个粗心的解决方案只跟踪​​总价值会认为他有足够的钱并给出错误的答案。 

另一个边缘情况是当一些较小的硬币出现在更高面额的硬币之后时：```
4
bronze
bronze
silver
gold
```正确的输出是：```
YES
```前两位顾客给了阿方索两枚铜币。 银币支付可以返还一枚铜币来办理。 最终的金金支付可以通过返还一银一铜的方式来处理。 仅检查每个硬币值是否出现足够次数的解决方案可能会错过排序要求。 

最终的边界情况是：```
3
bronze
silver
gold
```正确的输出是：```
NO
```在获得铜牌后，阿方索获得了一枚铜牌。 白银支付成功，留下一枚银币。 支付金币需要三枚铜币，而阿方索只有一枚银币。 银币不能找零，因为它值两枚硬币而不是三枚。 

# 方法

 一个简单的方法是模拟阿方索可以做出改变的每一种可能的方式。 对于每个客户，程序可以尝试不同的硬币组合，总和为所需的找零，并递归地继续。 这是正确的，因为每一个可能的决策顺序都被考虑了，但它很快就变得不可能了。 在最坏的情况下，每个黄金客户都会引入几种可能的方法来创造价值三枚铜币的零钱，并且探索这些分支会导致指数行为。 

硬币系统的结构给出了一条更简单的路线。 由于每种面额恰好是前一种面额的两倍，因此较大的硬币总是比较小的硬币更有价值且灵活性较差。 对于未来的客户来说，唯一重要的是阿方索目前拥有多少铜币和银币，因为找零从来不需要金币。 交易后，他的收藏中始终保留着一枚金币。 

关键的观察是改变可以贪婪地进行。 一位白银客户只需要一枚铜币。 黄金客户需要三枚价值的铜币。 提供三枚铜币零钱的最佳方法是尽可能使用一枚银币和一枚铜币，因为这样可以为未来的白银客户保留更多的铜币。 如果实在不行的话，就只剩下三枚铜币了。 

蛮力之所以有效，是因为它探索了每一种有效的改变方式，但却失败了，因为选择的数量增长得太快。 硬币值的二进制性质消除了这种歧义，让我们在处理该行一次时仅维护必要的硬币计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 客户数量呈指数级增长| O(n) | 太慢了 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 # 算法演练

 1. 维护阿方索拥有的铜币、银币和金币数量的计数器。 最初所有三个计数器都为零。 
2. 从队列前面一一读取顾客，并将收到的硬币添加到阿方索的收藏中。 收到的硬币不能用于支付该物品，因为交易已经发生，因此它成为他可用硬币的一部分。 
3. 如果客户使用铜币付款，则无需找零，因为付款与价格完全一致。 
4. 如果顾客用银币付款，请取出一枚铜币作为零钱。 如果没有铜币，就不可能为顾客提供服务。 
5. 如果顾客用金币付款，请取出价值三枚铜币的零钱。 最好使用一枚银币和一枚铜币，因为这样可以保留剩余的铜币以供以后的银币支付。 如果不可能，请使用三枚铜币。 如果两个选项都不存在，则该过程失败。 
6. 如果每个客户都处理成功，则输出`YES`。 否则输出`NO`在无法产生变化的第一点上。 

为什么它有效：

 不变的是，在成功为每个客户提供服务后，存储的硬币数量恰好代表阿方索在完成迄今为止所有交易后拥有的硬币。 对于银币付款，唯一可能需要的零钱是一枚铜币。 对于金币支付，返回三枚铜币的有效方式要么是一枚银币加一枚铜币，要么是三枚铜币。 贪婪的选择是安全的，因为用两枚铜币代替一枚银币只会降低阿方索的灵活性。 保留较大的硬币，同时首先花费较小的价值，至少可以提供同样多的能力来服务所有未来的客户。 由于每个客户都是使用保留此不变量的有效交易来处理的，因此最终答案是正确的。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    bronze = 0
    silver = 0
    gold = 0

    for _ in range(n):
        coin = input().strip()

        if coin == "bronze":
            bronze += 1
        elif coin == "silver":
            silver += 1
            if bronze == 0:
                print("NO")
                return
            bronze -= 1
        else:
            gold += 1
            if silver > 0 and bronze > 0:
                silver -= 1
                bronze -= 1
            elif bronze >= 3:
                bronze -= 3
            else:
                print("NO")
                return

    print("YES")

if __name__ == "__main__":
    solve()
```这三个变量仅存储未来客户所需的信息。 金币被算在内，因为收到后金币属于阿方索，但从不参与找零。 

对于白银支付，代码首先添加银币，然后删除一枚铜币。 该订单是正确的，因为顾客在阿方索归还零钱之前给了硬币。 

对于黄金支付，代码首先保留金币，然后检查创建三个铜币找零的两种有效方法。 优选分支使用银币和铜币。 后备分支使用三枚铜币。 检查是在减法之前写入的，因此计数器永远不会变为负数。 

Python 整数不会溢出，并且该算法仅使用几个变量，因此即使对于最大数量的客户，它仍然保持高效。

 # 边缘情况

 对于第一个边缘情况：```
3
gold
gold
gold
```该算法从零硬币开始。 第一个黄金顾客给了阿方索一枚金币，但算法会检查是否存在价值三枚铜币的零钱。 一银加一铜，三铜钱都没有，所以立即打印`NO`。 这符合真实的过程，因为金币不能分割成更小的硬币。 

对于顺序敏感的情况：```
3
bronze
silver
gold
```继青铜顾客之后，阿方索拥有一枚铜币。 白银顾客给了一枚银币，拿走了一枚铜币，只留下一枚银币。 黄金客户需要三个铜币找零。 该算法找不到银铜币对或三枚铜币，因此拒绝该序列。 

对于成功的边界情况：```
4
bronze
bronze
silver
gold
```该算法积累两枚铜币，花费一枚用于支付银币，然后使用剩余的铜币与银币一起支付金币。 每笔交易都保留了这样的不变性：阿方索存储的硬币正是他为客户提供服务后的真实硬币，因此最终答案是`YES`。
