 ## 解决方案
 ## 问题理解

 我们给出了几个等长的数字串。 每个字符串中的数字都位于错误的位置，但对所有这些数字都应用了相同的未知重新排列。 我们的任务是自己选择位置的重新排列，以便在移动每个字符串中的数字后，最大结果数字和最小结果数字之间的差异尽可能小。 

输出就是这个最小可能的差异。 

输入的关键部分是位数少。 长度最多为 9，这意味着可能的位置重新排列总数最多为 9!，即 362880。这个长度足够大，需要尝试每种排列，但又足够小，可以对所有排列进行完整搜索。 代码的数量最多为 100 个，因此根据所有代码检查一种排列也很便宜。 对于每个可能的数字排序尝试所有可能的转换值的解决方案仍然适合，因为搜索空间受到阶乘界限的限制。 

危险案件往往来自于容易被忽视的细节。 前导零必须保持有意义，因为代码的长度始终恰好是 k 位。 例如，如果输入是：```
2 2
01
10
```正确答案是`9`。 两种可能的安排是`01,10`差异 9 和`10,01`具有相同的差异。 治疗`01`因为重新排列之前的整数 1 不会破坏这种特殊情况，但通常它可能会丢失位置信息并导致不正确的转换。 

重复的数字是错误的另一个来源。 考虑：```
3 3
111
121
131
```正确答案是`20`。 交换两个相等的数字位置不会改变任何内容，但是假设每个排列都会创建唯一结果的实现可能会浪费时间或意外地错误地删除有效排列。 

最后的边缘情况是所有代码都相同：```
3 2
55
55
55
```答案是`0`。 任何排列都会使所有值相等，因此最大值和最小值保持相同。 

## 方法

 直接的方法是尝试 k 位数字位置的所有可能的排序。 对于每个顺序，我们使用该顺序转换每个恢复代码，跟踪最小和最大转换值，并用它们的差异更新答案。 

这种蛮力是正确的，因为每种可能的常见重排都经过明确测试。 如果存在最佳重排，它就会出现在生成的排列中。 

由于 k 很小，蛮力变得实用。 当 k = 9 时，只有 362880 种排列。 检查一种排列需要查看最多 100 个数字。 一个逐位重建每个转换后的数字的简单实现大约执行 362880 × 100 × 9 次操作，即大约 3.26 亿次小操作。 

主要的改进不是算法思想的不同，而是仔细的表示。 我们不是重复转换字符串，而是预先计算每个数字的每个原始数字位置的贡献。 当排列将位置置于特定的十进制权重时，我们仅添加存储的贡献。 这保留了阶乘枚举，但使每次检查速度更快。 

暴力破解之所以有效，是因为可能的数字顺序数量很少。 仅当数字长度变得更大时才会失败，此时阶乘增长变得不可能。 k 永远不会超过 9 的观察结果让我们可以将问题简化为对所有位置排列进行穷举搜索。

 | ---| ---| ---| ---|
 | 蛮力 | O(k!·n·k) | O(k!·n·k) | O(n·k) | O(n·k) | 已接受并优化 |

 ## 算法演练

 1. 读取所有代码并分别存储每个代码的数字。 保留数字而不是立即将所有内容转换为整数可以保留原始的 k 位结构。 
2. 预先计算每个代码的每个数字位置的贡献。 对于每个代码位置和每个小数位，存储该数字如果放置在那里将添加的值。 在排列搜索期间，这避免了重复的字符串操作。 
3. 生成 k 个原始位置的每个排列。 排列表示从最高有效数字到最低有效数字的最终位置顺序。 
4. 对于当前排列，通过组合所选位置的预先计算的贡献来计算每个变换后的数字。 最大和最小变换值决定了这种排列产生的差异。 
5. 更新全局最小答案，与当前安排有所不同。 检查完所有排列后，该值就是所需的结果。 

这样做的原因是每个有效的解决方案都是数字位置的一种排列。 搜索会访问每一个这样的排列，并为每一个排列计算由该重新排列产生的确切的最大值和最小值。 由于该算法会比较所有可能的重新排列，因此它不会错过更好的答案。 

## Python 解决方案```python
import sys
from itertools import permutations

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    codes = [input().strip() for _ in range(n)]

    digits = [[ord(c) - 48 for c in s] for s in codes]

    weights = [10 ** i for i in range(k - 1, -1, -1)]

    contrib = []
    for row in digits:
        contrib.append([row[j] * weights[i] for j in range(k) for i in range(k)])

    pre = []
    for row in digits:
        cur = []
        for pos in range(k):
            for place in range(k):
                cur.append(row[pos] * weights[place])
        pre.append(cur)

    ans = 10 ** k

    for perm in permutations(range(k)):
        best = -1
        worst = 10 ** k

        for row in pre:
            value = 0
            base = 0
            for pos in perm:
                value += row[pos * k + base]
                base += 1

            if value > best:
                best = value
            if value < worst:
                worst = value

        diff = best - worst
        if diff < ans:
            ans = diff

    print(ans)

if __name__ == "__main__":
    solve()
```该代码存储每个原始数字位置可能的加权贡献。 置换循环将原始位置分配给输出位置，因此内部计算仅执行加法。 

排列中数字的顺序很重要。 排列的第一个元素被放置在最重要的位置，这就是为什么权重是从十的最高幂向下生成的。 

变量`best`和`worst`代表当前排列产生的最大和最小数字。 它们会针对每个排列进行重置，因为每种排列都描述了不同的可能的密码重建。 

对于这个问题，Python 整数不会溢出，因为最大的数字只有九位，但实现仍然避免了不必要的转换和重复求幂，以保持较低的运行时间。

## 测试用例```python
import sys
import io
from itertools import permutations

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, k = map(int, input().split())
    codes = [input().strip() for _ in range(n)]

    ans = 10 ** k

    for perm in permutations(range(k)):
        mn = 10 ** k
        mx = -1
        for s in codes:
            value = int(''.join(s[i] for i in perm))
            mn = min(mn, value)
            mx = max(mx, value)
        ans = min(ans, mx - mn)

    return str(ans)

assert run("""2 2
12
32
""") == "2", "sample 1"

assert run("""4 4

0141
5581
1581
""") == "1017", "sample 2"

assert run("""2 1
0
9
""") == "9", "single digit boundary"

assert run("""3 2

55
""") == "0", "all equal values"

assert run("""3 3

""") == "99", "leading zero handling"

 ## 边缘情况

 对于前导零的情况：```
3 3
001
100
010
```该算法将每个代码视为三个单独的数字位置。 排列可以移动零，但不能删除它们。 每个排列都被评估为一个三位数，因此输出保持正确。 

对于重复的数字：```
3 2
55
55
55
```每个排列都会创建完全相同的转换值。 每次迭代期间最大值和最小值都相等，因此答案保持为零。 

对于具有较大长度的相同代码：```
3 4
1234
1234
1234
```每一种可能的重新排列都会产生三个相同的数字。 搜索仍然检查所有排列，但每个排列在找到最大值和最小值后立即产生零差。 

对于尽可能少的代码：```
2 1
3
8
```只有一种可能的数字位置排序。 该算法直接评估两个变换后的值并返回它们的差值，即 5。
