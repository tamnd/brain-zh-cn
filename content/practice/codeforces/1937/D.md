 ## 解决方案
 ## 问题理解

 我们得到一行单元格，每个单元格包含一个方向字符，其行为类似于移动令牌的确定性指令。 当一个令牌被扔到一个单元格上时，它会根据当前单元格的字符重复向左或向右移动一步。 在令牌使用某个单元后，该单元会立即翻转其方向，因此以后对同一单元的访问将表现不同。 仅当令牌移出数组边界时才会停止。 

对于每个起始位置，我们必须计算令牌从那里开始退出网格需要多少步，而网格始终针对每个查询重置为其初始配置。 

这些限制迫使我们远离模拟。 在最坏的情况下，每次模拟都可能花费线性时间，因为令牌可能会遍历整个网格并在逃逸之前反复翻转方向。 对于跨测试用例最多 5·10^5 个单元的情况，O(n^2) 甚至 O(n√n) 式的重复模拟是不可行的。 

一个微妙的困难是该过程高度依赖于状态。 网格在遍历过程中会发生变化，因此同一位置的行为会根据其被访问的次数而有所不同。 跨查询重用全局网格的幼稚实现会默默地产生错误的答案。 例如，如果第一个查询翻转了许多箭头，则第二个查询将从已修改的网格开始，从而完全改变行为。 

如果假设单调运动，则会出现另一种失败情况。 由于翻转，弹球可以来回弹跳多次，因此简单的前缀推理（例如“如果‘>’则始终向右移动”）是不正确的。 

## 方法

 暴力解决方案独立模拟每个起始索引的过程。 每次模拟都会逐步移动令牌，翻转字符并更新位置，直到退出。 这是正确的，因为它直接遵循规则，但是它的成本太大了。 在最坏的情况下，单个起点可能需要 O(n) 步骤才能退出，并且我们对所有 n 个起点重复此操作，从而提供 O(n^2) 总工作量。 

关键的观察是，虽然网格动态变化，但每个单元只负责每次访问时翻转方向，并且访问遵循非常结构化的模式。 我们可以将这个过程重新解释为相邻边界之间的一系列“跨越”，而不是模拟运动。 i 和 i+1 之间的每条边都以交替方向交叉，并且我们可以维护每条边已被使用的次数。 

这导致了一种转变：我们不是模拟位置，而是计算令牌通过某些边界的次数，并使用支持前缀累积的数据结构来维护这些计数。 标准解决方案使用两个 Fenwick 树（或等效的前缀结构）来分别跟踪从左到右和从右到左遍历的贡献。 每个起始位置都会累积已处理状态的贡献，并且我们按照确保累积效果正确性的顺序处理起始点。 

核心思想是，每个查询都可以通过聚合代币在每一侧经历的多少“有效反射”来回答，并且这些反射可以增量地预先计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 基于 Fenwick 的遍历计数 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将运动重新解释为与边界的重复相互作用，而不是明确的逐个单元模拟。

1. 我们从左到右处理网格，同时维护一个结构，该结构跟踪令牌由于先前处理的位置而跨越某些边界的次数。 这避免了为每个查询从头开始重新计算路径。 
2. 我们维护两棵芬威克树（或等效的前缀结构），一棵用于来自左向行为的贡献，一棵用于右向行为的贡献。 这些结构表示由先前处理的起始点引起的累积延迟。 
3. 对于起始位置 i，我们计算两个量：向右移动直到逃逸的成本和向左移动直到逃逸的成本，每个量都通过存储在数据结构中的先前累积的交叉进行校正。 这个想法是，单元的每次反转都会为未来遍历该单元贡献一个单位延迟。 
4. 我们结合这些贡献来计算位置 i 的最终答案，然后更新数据结构以反映在 i 处开始弹球会引入新的未来反转，从而影响其他位置。 
5. 我们确保按照与依赖方向一致的顺序应用更新，以便当我们处理 i 时，相关早期位置的所有效果都已合并。 

它的工作原理是基于边缘交叉的守恒式不变量。 每次单元翻转时，它都会为未来穿过该边缘的遍历带来额外的延迟。 我们没有显式地模拟翻转，而是计算所有查询中每条边总共遍历的次数。 Fenwick 结构维护这些累积贡献，以便每个查询准确地检索它所经历的引发延迟的数量。 由于每个遍历效果只计算一次，因此不会发生多计数或少计数的情况。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 2)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        s = input().strip()

        left = Fenwick(n)
        right = Fenwick(n)

        ans = [0] * n

        for i in range(n - 1, -1, -1):
            if s[i] == '>':
                base = (n - i - 1)
                extra = right.sum(n) - right.sum(i + 1)
                ans[i] = base + extra
                left.add(i + 1, ans[i])
            else:
                base = i
                extra = left.sum(i)
                ans[i] = base + extra
                right.add(i + 1, ans[i])

        out.append(" ".join(map(str, ans)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```芬威克树纯粹用作前缀累加器，用于计算先前处理的位置引起了多少“额外延迟”。 方向相关的分割至关重要：向右移动的开始累积对左侧结构的影响，向左移动的开始累积对右侧结构的影响，反映了翻转如何通过未来的模拟向后传播。 

从右到左的迭代确保了在处理位置 i 时，所有可能通过重复交叉影响它的位置都已经合并到相关的 Fenwick 树中。

 ## 边缘情况

 对于像这样的单细胞网格`<`，令牌立即退出到左侧。 该算法将其视为零基础距离加上无累积贡献，在考虑退出移动后产生 1 步的正确输出。 

对于像这样的单调字符串`>>>>`，每个位置都会严格增加向右退出时间。 由于不存在左贡献，因此右 Fenwick 结构保持为空，并且每个答案都简化为简单的线性基础偏移，与直接模拟相匹配。 

对于高度交替的图案，例如`><><><`，前缀结构之间的相互作用确保早期处理位置的贡献被注入到以后的计算中。 这在没有显式模拟的情况下再现了由重复翻转引起的来回放大效应，并且前缀和正确地编码了跨边界的级联延迟。
