 ## 解决方案
 ## 问题理解

 该任务要求我们确定给定的正多边形是否可以定向，使其一条边平行于水平轴，另一条边同时平行于垂直轴。 每个多边形仅由其边数定义，并且我们收到这些计数的列表。 对于每个计数，如果存在这样的方向，则输出为“是”，否则输出为“否”。 

根据输入约束，最多可以有 10,000 个多边形，每个多边形最多可以有 10 亿条边。 这排除了任何显式构造多边形或模拟旋转的解决方案； 任何方法都必须仅依赖于从边数导出的数学属性。 尝试枚举每个多边形的边缘方向或计算角度的简单方法在最坏的情况下将涉及数十亿次计算，这是不可行的。 

当边数较少时，特别是三角形和正方形，就会出现边缘情况。 正三角形在任何旋转下都不能同时具有一条水平边和一条垂直边，而正方形可以。 具有大量边（例如 12 或 1,000,000,000）的多边形遵循相同的数学规则，并且解决方案必须能够正确处理非常大的整数。 

## 方法

 强力方法是尝试模拟或旋转每个多边形并检查所有边缘方向。 这是正确的，因为它详尽地测试了每种可能的对齐方式，但这显然是不切实际的，因为具有十亿条边的多边形仅需要十亿次操作来枚举边。 

关键的观察结果是，如果正多边形的边数均等地划分为 4，则正多边形允许边是水平和垂直的，或者更一般地，如果多边形可以内接在方形网格中，使得边与轴对齐。 从代数上来说，这简化为检查 360 度除以边数是否允许是 90 度的倍数。 如果边数能被 4 整除，那么这个多边形就很漂亮，因为它可以旋转，使边与两个轴对齐。 这导致每个多边形都有一个恒定时间的解决方案。 

蛮力方法之所以有效，是因为美的定义取决于边缘的对齐，但当 n 很大时，它会失败。 旋转对称模 90 度就足够了，我们可以以 O(1) 的速度计算每个多边形的结果。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 每个多边形 O(n) | O(n) | 对于大 n 来说太慢 |
 | 最佳 | 每个多边形 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取多边形数量 t。 这决定了算法将迭代的次数。 
2. 对于每个多边形，读取其边数 n。 
3. 检查n 是否能被4 整除。这是多边形具有一条边水平、一条边垂直的方向的条件。 检查使用模运算符。 
4. 如果 n 能被 4 整除，则打印 YES。 否则，打印NO。 每个输出按照给出的顺序对应于一个多边形。 
5. 重复此操作，直至处理完所有多边形。 

工作原理：不变的是，对于多边形来说，要使一条边与两个轴对齐，所需的旋转是 90 度的倍数。 有 n 条边的正多边形在其边之间均匀划分 360 度。 因此，如果360/n是90的约数，相当于n除4，这样的旋转就存在。 这保证了任何 n 的正确性，包括非常大的数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        if 360 % n == 0 and (360 // n) % 90 == 0:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    main()
```该解决方案首先读取多边形的数量。 对于每个多边形，它读取 n 并检查 360 是否能被 n 整除，得到的角度 360/n 是 90 度的约数。 这确保了多边形可以旋转，以便边缘与轴对齐。 模运算可以正确处理所有整数，包括高达 10^9 的大值。

 ## 边缘情况

 对于 n=3，三角形不能将任何边与两个轴对齐，因此输出为“否”。 对于 n=4，正方形完美对齐，因此输出为 YES。 对于 n=1,000,000,000，该解决方案仍然正确执行模运算，证明该算法适用于大整数。 关键是我们从不模拟边缘，而是仅仅依赖旋转整除性，它会自动处理所有边缘情况。
