 ## 问题理解

 我们得到一个必须分成组的整数集合，其中每个组被分配给不同的朋友。 每个朋友都会收到固定数量的整数，并且每个整数必须恰好使用一次。 

朋友的满意度仅取决于其指定组中的最小和最大值。 具体来说，如果一个朋友收到一组数字，那么他们的幸福感就是该组中最小值和最大值的总和。 总目标是将所有数字分配到给定的组大小中，以使所有朋友的幸福值总和最大化。 

从根本上来说，这是一个排序数组的划分问题，其中只有每个组的极值很重要，这表明组的内部元素与目标无关。 

约束条件很大：所有测试用例的整数总数最多为 200,000。 这立即排除了每次测试的任何指数甚至二次推理。 对每个测试用例进行排序是可以接受的，但排序后需要任何超出线性或近线性的结果。 

一种简单的方法是尝试将数字分配给组并动态重新计算最小值和最大值。 即使贪婪但未排序的分配也会失败，因为元素的贡献完全取决于它是否成为某个组的边界。 

当大值和小值在组之间混合不良时，就会出现微妙的失败情况。 例如，如果我们贪婪地打包连续的块而不考虑大小，我们可能会将一个非常大的值锁定到一个不与小值配对的组中，从而失去潜在的贡献。 同样，将小值放入大组中会降低它们在其他地方充当最小值的潜力。 

关键的观察结果是，只有每组中的第一个和最后一个元素很重要，并且我们可以完全控制排序后的分组。 

## 方法

 暴力策略会尝试所有可能的方法将已排序的数组划分为给定大小的组。 即使我们修复排序，分配组之间边界的方法数量也会随着 n 和 k 的组合而增长，因为我们在 n−1 个间隙中选择 k−1 个切割位置。 然后，每个分区都需要计算每组的最小值和最大值，从而进行 O(n) 评估。 即使 n 约为 30，这也会变得天文数字般大。 

一旦我们对数组进行排序，结构就会大大简化。 作为组最小值和最大值的唯一有用的候选者是最小和最大的剩余元素。 这表明我们应该始终从排序数组中取极端值。 

现在考虑一个团体如何做出贡献。 大小为 w 的一组贡献其最大减去最小结构。 如果我们考虑分配极值，每个组总是会从最大的可用元素中获取最大值。 困难在于决定一个群体何时应该只“消耗”一个大元素，而不是将其与一个小元素配对以形成完整的贡献。 

关键的见解是按大小顺序处理组。 单元素组很特殊：它们的贡献是相同元素的两倍，因此应该为它们分配最大的可用数字，因为它们可以最大化直接增益。 处理完所有大小为 1 的组后，剩余组的大小必须至少为 2。对于这些组，可以认为每个组都需要一个“顶部”元素和一个“底部”元素。 为了最大化 (max + min) 的总和，我们希望最大值尽可能大，最小值也尽可能大，但最小值受到未分配元素数量的限制。

这会导致排序数组两端的贪婪配对。 我们首先将最大元素分配为所有组的最大值，然后将最小的剩余元素分配为除最大组之外的所有组的最小值，其中重叠会被仔细管理。 

更精确和标准的解释是：对数组和权重进行排序。 将每个组扩展为​​贡献。 每组大小 w 贡献一个“最大槽”和一个“最小槽”。 然而，如果 w == 1，两个槽都会折叠成同一个元素，使其贡献加倍。 对于 w > 1，我们必须为每个组分配一个最大值，并将最小槽分配给大小 > 1 的组。最佳策略是贪婪地将最小的剩余元素与受益最多的组配对，而最大的元素则分配给贡献最大项的组。 

这减少了用两个指针管理排序多重集的问题。

 ## 算法演练

 1. 按非降序对整数数组进行排序。 这使我们能够有效地访问最小和最大的剩余元素。 
2. 按非降序对组大小进行排序。 较小的群体更容易满足，并且在分配极值方面具有更大的灵活性。 
3. 初始化两个指针：一个位于数组开头（对于小值），一个位于数组末尾（对于大值）。 
4. 初始化一个变量来累积答案。 
5. 首先处理大小为 1 的所有组。对于每个这样的组，取出最大的剩余元素并将其与答案相加两次，然后将右指针向左移动 1。 这是最优的，因为通过使用最大的可用数量，大小为 1 的群体的贡献最大化。 
6. 处理完 size-1 组后，按大小降序处理剩余组。 对于每个组，将其最大值指定为当前最大的剩余元素，然后递减右指针。 这确保了大值有助于最大化。 
7. 对于大小大于 1 的组，将其最小值指定为当前最小的剩余元素，然后递增左指针。 这确保我们仅在被迫填充最小位置时才使用较小的值。 
8. 将每组的所有贡献求和为最大值 + 最小值。 

### 为什么它有效

 该算法在用作最大值的元素和用作最小值的元素之间保持严格的分离。 每个组都贡献一个最大值，每个组都贡献一个最小值，除了大小为 1 的组两次贡献相同的元素。 

总是将最大的剩余元素与最大值配对的贪婪选择是安全的，因为最大值在各个组之间做出积极且独立的贡献。 一旦最大值被固定，将最小的剩余值分配给最小值是最佳的，因为它为未来的最大值保留了更大的值，这些值在总和中具有更高的边际贡献。 由于每个元素仅使用一次，因此这种双边贪婪分配确保重新排列不会增加总和，而不会减少同等或更高影响的另一项。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        w = list(map(int, input().split()))
        
        a.sort()
        w.sort()
        
        l, r = 0, n - 1
        ans = 0
        
        # handle size-1 groups first
        i = 0
        while i < k and w[i] == 1:
            ans += 2 * a[r]
            r -= 1
            i += 1
        
        # remaining groups
        groups = w[i:]
        
        # process from largest to smallest group
        for sz in reversed(groups):
            ans += a[r]   # max
            r -= 1
            
            if sz == 1:
                ans += a[r]
                r -= 1
            else:
                ans += a[l]
                l += 1
                # remaining internal elements are irrelevant
        
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案对两个数组进行排序，以便始终可以访问极值。 指针`r`保留用于分配组的最大值，而`l`当组的大小至少为 2 时，用于最小值。首先处理大小为 1 的组，因为它们有效地消耗两个大元素，从而最大化其双倍​​贡献。 对于较大的群体，每个群体贡献一个大元素和一个小元素，并且任何中间元素都是无关紧要的，因为只有极值重要。 

必须小心地首先处理所有大小为 1 的组，否则大值可能会被浪费为较大组中的最小值。 反转剩余的组列表可确保较大的组在需要时更早访问较大的最大值。

 ## 边缘情况

 一个关键的边缘情况是当所有组的大小都为 1 时。在这种情况下，每个元素对答案的贡献都是两倍。 该算法通过重复获取最大的剩余元素来处理这个问题，确保最大的加倍贡献。 

另一种边缘情况是只有一个大组和许多小值时。 该算法首先从右侧贪婪地分配最大值，确保大值不会被浪费为最小值。 其余元素自然会填充最小位置。 

当所有值都相等时，任何分区都会产生相同的结果。 该算法仍然表现正确，因为无论顺序如何，每个分配都会添加相同的贡献。 

当团体规模差异很大时，就会出现一种微妙的情况。 通过首先处理单例组，该算法可以防止较大的值在较大的组中被用作最小值，从而保留它们的最佳使用作为最大值。
