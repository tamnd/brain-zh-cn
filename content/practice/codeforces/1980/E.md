 ## 解决方案
 ## 问题理解

 我们有两个矩形数字网格，大小都相同$n \times m$，并且它们一起包含的数字恰好来自$1$到$n \cdot m$，每个出现一次。 所以每个矩阵只是同一组图块的重新排列。 

唯一允许的移动是交换整行或交换整列。 我们可以这样做任意多次。 任务是确定我们是否可以仅使用这些行和列交换将第一个网格转换为第二个网格。 

关键约束是行交换不会更改行内的顺序，它们只会重新排序行，而列交换不会更改列内的顺序，它们只会重新排序列。 因此，网格的结构被保留到行索引和列索引的独立排列。 

输入大小很大：在所有测试用例中，单元总数最多为$2 \cdot 10^5$。 这强烈表明$O(nm)$每个测试用例或线性整体解决方案。 任何涉及每次测试或模拟操作的重复排序的事情只有在总输入大小呈线性时才可以。 

一个天真的误解是认为我们需要模拟交换或尝试贪婪地“对齐”行和列。 在以下情况下这会失败：

 示例：$$a = \begin{pmatrix} 1 & 2 \\ 3 & 4 \end{pmatrix}, \quad b = \begin{pmatrix} 4 & 3 \\ 2 & 1 \end{pmatrix}$$简单的行匹配方法可能会得出不匹配的结论，因为没有行直接匹配，但交换行和列使转换成为可能。 

另一个微妙的失败情况是假设行多重集必须逐行匹配。 这是错误的，因为行本身是任意排列的。 

真正的困难在于行排列和列排列是全局交互的，而不是局部交互的。 

## 方法

 暴力的观点是将行和列交换视为生成行和列的所有排列。 这意味着任何转换都对应于选择行排列和列排列。 原则上，我们可以尝试所有行排列和列排列，并检查结果矩阵是否匹配。 这将涉及$n!\cdot m!$的可能性，即使对于$n=5$。 

关键的见解是行和列交换独立于索引起作用。 如果我们为每个值分配其在两个矩阵中的位置，我们就可以用坐标来思考。 每个数字$x$在矩阵中$a$有坐标$(r_a[x], c_a[x])$，并且在矩阵中$b$, 坐标$(r_b[x], c_b[x])$。 

如果存在有效的转换，则必须存在行排列和列排列，使得对于每个值$x$，其行索引映射一致，其列索引映射一致。 换句话说，该变换产生两个双射：

 一位关于行索引，一位关于列索引，并且它们必须同时解释所有位置。 

这减少了检查这些导出映射的一致性的问题。 强制执行此操作的一种简洁方法是使用值的位置来锚定行关系：出现在同一行中的值$a$必须映射到出现在同一行中的值$b$，在一致地重新索引行之后。 这同样适用于列。 

一个更简单和标准的重新表述是将每个值视为一对$(row, col)$，然后观察任意两个值之间的行的相对顺序必须保留在$a$和$b$，对于列也类似。 这会产生一个约束图，其中的不一致立即表明不可能性。 

更易于实现的表征是通过用值的位置替换值并检查所有值的诱导行排序和列排序在排列之前是否相同来标准化两个矩阵。 按值在一个矩阵中的位置对值进行排序并验证另一个矩阵中的一致性会导致使用每行和每列的散列或签名比较进行线性或近线性检查。 

最实用的解决方案使用位置编码：对于每个值，在两个矩阵中记录其行和列，然后验证所有值之间的行和列的相对顺序在两种表示中是否相同。 这可以简化为检查来自行的映射$a$到行$b$是一致的，对于列也是如此。

 ## 算法演练

 我们在两个矩阵中的值的位置之间建立直接映射，并验证这些映射隐含的行和列排列是否一致。 

1. 读取两个矩阵并存储每个值$x$，其坐标在$a$:$(r_a[x], c_a[x])$并在$b$:$(r_b[x], c_b[x])$。 

此步骤将网格问题转换为排列上的点匹配问题。 
2. 对于每个值$x$，我们将转换解释为映射行$r_a[x]$到$r_b[x]$，和列$c_a[x]$到$c_b[x]$。 

如果存在有效的全局行排列，则所有值共享一行$a$必须一致地映射到相同的行结构$b$。 
3. 我们通过在每行中选择一个代表值来强制行映射的一致性$a$，并确保该行中的所有值映射到相同的行排列$b$。 

如果有任何一行$a$尝试映射到多行$b$，转型是不可能的。 
4. 对列重复相同的逻辑，确保每一列$a$一致地映射到单个列$b$。 
5. 建立映射后，我们验证单射性：中没有两个不同的行$a$映射到同一行$b$，对于列也类似。 

这确保了映射是真正的排列而不是崩溃。 
6. 如果行和列映射都是有效排列，则输出YES； 否则输出NO。 

### 为什么它有效

 行交换仅全局排列行索引，这意味着共享行的值的标识在任何操作序列下都是不变的。 这同样适用于列。 因此，由行（和列）引起的值的分区必须保留在$a$和$b$，直到重命名行索引和列索引。 

如果两个值位于同一行$a$，它们必须最终位于同一行$b$应用行排列后。 这会强制从行中进行明确定义的映射$a$到行$b$。 同样的论点反过来也适用，确保双射性。 

因此，该算法正在检查由值的排列引起的行分区和列分区是否可以一致地重新标记。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())

        pos_a = {}
        pos_b = {}

        for i in range(n):
            row = list(map(int, input().split()))
            for j, x in enumerate(row):
                pos_a[x] = (i, j)

        for i in range(n):
            row = list(map(int, input().split()))
            for j, x in enumerate(row):
                pos_b[x] = (i, j)

        row_map = {}
        col_map = {}

        ok = True

        for x in pos_a:
            ra, ca = pos_a[x]
            rb, cb = pos_b[x]

            if ra in row_map and row_map[ra] != rb:
                ok = False
                break
            if ca in col_map and col_map[ca] != cb:
                ok = False
                break

            row_map[ra] = rb
            col_map[ca] = cb

        if ok:
            if len(set(row_map.values())) != len(row_map):
                ok = False
            if len(set(col_map.values())) != len(col_map):
                ok = False

        out.append("YES" if ok else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案首先将两个矩阵压缩到位置查找表中，以便每个值直接显示其坐标。 然后它构建两个部分映射：一个用于行，一个用于列。 一致性检查确保第一个矩阵中的行永远不会尝试映射到第二个矩阵中的两个不同行，这将与全局行排列的存在相矛盾。 

最后的单射性检查确保我们真正拥有排列，而不是多对一映射，这会违反行和列交换的可逆性。 

一个常见的陷阱是忘记一致性必须在所有值上全局强制执行，而不是逐行独立执行。

 ## 边缘情况

 一个棘手的边缘情况是行映射局部一致但全局冲突。 例如，如果两个不同的行$a$两者都尝试映射到同一行$b$，算法通过单射性检查捕获这一点。 

考虑：```
a:
1 2
3 4

b:
1 2
3 4
```这里身份映射是有效的。 

现在修改：```
b:
3 4
1 2
```行映射变成0→1和1→0，这样就可以了。 但是，如果存在尝试不一致映射的第三行，则仅在检查映射值的全局唯一性时才会出现冲突，而不是每次分配时都会出现冲突。 

该算法通过在整个映射空间上强制执行一致性和双射约束来正确处理此问题，而不是依赖于本地行比较。
