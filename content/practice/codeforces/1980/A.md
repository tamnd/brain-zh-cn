 ## 解决方案
 ## 问题理解

 每个测试用例都描述了 Vlad 已经拥有的一个小问题集以及他想要组织的目标轮数。 每个问题都有从 A 到 G 的七个可能的难度标签之一。一轮只需要一个问题，但在所有轮次中，Vlad 希望确保他能够为这些轮次所需的每个难度级别提供足够的问题。 

对于每个测试用例，我们都会得到一组现有问题和若干轮 m。 每一轮有效地消耗一个要求，并且在所有 m 轮中，Vlad 需要能够满足所有可能出现的难度字母的需求。 由于该声明的示例显示缺失的字母被“填充”，因此真正的任务减少为检查覆盖范围：对于七种难度类型中的每一种，已经存在多少个难度类型，以及必须创建多少个额外的字母，以便在所有轮次中，可以填充所有必需的槽位。 

约束足够小，每个测​​试用例都可以通过直接计数来处理。 当 n 最大为 50，t 最大为 1000 时，即使每个测试用例的 O(n) 也是微不足道的。 任何简单地计算字符频率并将其与所需阈值进行比较的解决方案都将立即运行。 

当一个或多个字母完全丢失时，就会出现一种微妙的失败情况。 例如，如果所有现有问题都是从B到G，但A不存在并且m至少为1，我们仍然必须根据需要计算A。 另一个极端情况是当频率严重倾斜时，例如许多 B 但没有 E，如果我们只推断总大小而不是每个字母的覆盖范围，这可能会导致计数不足。 

关键是问题不是重新排列或分组问题。 这纯粹是为了确保每个所需的难度类型在构建的最终池中至少出现 m 次。 

## 方法

 思考这个问题的一种强力方法是逐一模拟构建回合。 对于每一轮，我们都会尝试首先分配现有问题，每当缺少所需的难度时，我们就会创建一个新问题。 这种方法可以通过迭代轮次和重复扫描可用计数来建模。 虽然这在概念上是可行的，但它是不必要的，因为我们会反复重新计算可用性，从而导致各轮的冗余工作。 

关键的观察结果是回合在结构上不相互作用。 每种难度类型必须独立满足与轮数需求成比例的要求。 由于每一轮都需要一个问题，并且只有在全局计算可用性的情况下才能重用每个难度，因此真正的要求很简单：对于七个字母中的每一个，确保我们在用于支持 m 轮的整个池中至少有 m 次出现。 

因此，我们不是模拟回合，而是直接将银行中每个字符的频率与 m 进行比较。 如果一个字母出现 cnt 次，那么我们需要 max(0, m − cnt) 个该字母的新问题。 将所有字母相加即可得出答案。 

这将问题简化为对 7 个符号进行固定大小的频率检查，这是每个测试用例的持续工作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(m * n) | O(1) | O(1) | 太慢而且没必要 |
 | 频率计数| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算从 'A' 到 'G' 的每个字符在给定字符串中出现的次数。 这给出了每种难度类型的当前供应量。 
2. 对于“A”到“G”范围内的每个字符，使用 max(0, m − current_count) 计算相对于 m 缺失的字符数。 这代表着为了解决这个困难必须创造多少新问题。 
3. 对七个字符中的所有缺失值求和。 
4. 输出总和作为测试用例的答案。

它之所以有效，与难度类型的独立性有关。 每个字母代表一个单独的需求范围。 一个字母的现有问题不能帮助满足另一个字母的要求，因此每个字母的缺陷是独立的。 最终的答案就是所有桶的总缺口。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        s = input().strip()

        freq = [0] * 7
        for ch in s:
            freq[ord(ch) - ord('A')] += 1

        ans = 0
        for i in range(7):
            if freq[i] < m:
                ans += (m - freq[i])

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先构建一个大小为 7 的频率数组，将每个字母 A 到 G 映射到一个索引中。 这可以避免以后重复扫描。 第二个循环直接计算每个字符相对于 m 的赤字。 减法是受保护的，因此我们只计算缺失值，而不计算剩余值。 

一个常见的错误是对差异求和而不将其限制为零，这会错误地将多余的字母视为负贡献。 另一个错误是与n而不是m进行比较，但要求是每轮覆盖，因此m是正确的目标。

 ## 边缘情况

 一个关键的边缘情况是某些字母根本不出现。 对于像 AAAAAAA 这样 m = 2 的输入，每隔一个字母的频率为零。 该算法为每个丢失的字母分配 2 的赤字，并为 A 分配零，因为它已经超过或满足取决于 m 的要求。 这确保了缺失的类别被完全计数而不是被忽略。 

另一个边缘情况是所有字母都已经足够了。 例如，m = 1 的 ABCDEFG 在所有类别中产生零缺失计数，并且该算法正确返回零，因为每个频率都满足或超过阈值。 

最后一种情况是极端倾斜，例如一个字母占主导地位。 计算仍然正确，因为每个字母都是独立处理的，因此一个类别中的盈余永远不会补偿另一类别中的赤字。
