[CF 1980B - 选择立方体](https://codeforces.com/problemset/problem/1980/B)

 **求解时间：** 1m 20s

 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景，其中编号立方体的集合根据它们的值重新排列。 一个立方体很特别，因为它是最受欢迎的，可以通过其原始位置来识别。 按值的降序对所有多维数据集进行排序后，Dmitry 从此排序列表中删除前 k 个多维数据集。 任务是确定最喜欢的多维数据集是始终被删除、从不删除，还是可能以任何一种方式进行，具体取决于值关系的解决方式。 

关键的困难在于排序并不完全确定。 当多个立方体共享相同的值时，排序后它们的相对顺序可以任意改变。 这意味着最喜欢的立方体的最终位置不是固定的； 这取决于等值元素的排列方式。 

输出必须将最喜欢的立方体分为三类。 如果在任何有效排序后它始终出现在前 k 个位置内，则答案为“是”。 如果它永远不会出现在前 k 个位置内，则答案是否定的。 否则，至少存在一种有效排序（其中已删除）和另一种有效排序（未删除），所以答案是“可能”。 

约束很小，n 最多为 100 个，最多 1000 个测试用例。 这立即排除了对相等元素的排列进行任何繁重的模拟或状态枚举。 尽管强力排列推理在理论上是可能的，但相等元素之间的重新排序数量会呈阶乘增长，并且是不必要的。 

当许多元素与最喜欢的元素具有相同的值时，就会出现微妙的边缘情况。 在这种情况下，收藏夹的位置在排序后可能会发生很大的变化。 

例如，如果所有多维数据集的值为 5、k = 3、n = 5，则最喜欢的多维数据集可以放置在排序顺序中的任何位置。 根据决胜局的不同，它最终可能会进入前三名之内或之外，所以答案是“也许”。 

当 k 非常大时，会出现另一种边缘情况。 如果 k = n，则无论顺序如何，所有立方体都始终会被删除，因此答案始终为“是”。 相反，如果 k = 0，则不会删除任何立方体，因此答案始终为“否”。 

## 方法

 暴力方法会尝试枚举所有遵循非递增值顺序的立方体排列。 这实际上意味着生成所有方法来排列等值组内的元素，并检查最喜欢的立方体是否出现在全部、没有或其中一些的前 k 个位置中。 虽然概念上很简单，但它会在每组重复项中分解。 在所有值都相等的最坏情况下，这将变为 n！ 排列，即使 n = 100 也是完全不可行的。 

关键的观察是排序仅修复不同值之间的相对顺序。 所有不确定性仅存在于等值块内。 因此，我们不需要模拟排列，只需推断有多少元素严格大于最喜欢的值，以及有多少元素等于它。 

在每个有效的排序顺序中，所有值严格大于最喜欢的元素都必须出现在最喜欢的元素之前。 这些位置是固定的并有助于保证前缀。 具有相同值的元素可以任意出现在最喜欢的元素之前或之后。 这会为最终排序数组中最喜欢的立方体创建一系列可能的位置。 

令higher 为严格大于a_f 的元素数量，equal 为等于a_f 的元素数量，包括收藏夹本身。 

最喜欢的元素最早可能的位置是当所有相等的元素在其块中排列在它之后时，因此它紧接在所有严格更大的元素之后。 该位置更高+1。 

最后可能的位置是当所有其他相等元素都放置在它之前时，因此它是其相等块中的最后一个。 那个位置更高+平等。

现在我们将这个范围与 k 进行比较。 如果最早的位置大于 k，则收藏夹永远不会被删除。 如果最新位置最多为 k，则始终将其删除。 否则，就会出现平局决胜局的分裂，将其置于任何一方，所以答案是“可能”。

 ## 算法演练

 1.读取n、f、k和数组a。 

最喜欢的立方体位于索引 f 处，因此我们存储它的值 x = a[f]。 
2. 计算有多少元素的值严格大于x。 

在任何排序排列中，这些元素必须出现在收藏夹之前。 
3. 计算有多少个元素的值等于x。 

该组包括收藏夹本身并确定其位置的灵活性。 
4. 将最爱的最早可能位置计算为大于 + 1。 

这对应于除最喜欢的元素之外的所有相等元素都放置在其后面的情况。 
5. 将最爱的最新可能位置计算为大于 + 等于。 

这对应于所有其他相等元素都放在它前面的情况。 
6. 将此范围与 k 进行比较。 

如果latest ≤ k，则每种可能的排序都将最喜欢的排序放在删除的前缀中，因此输出YES。 
7. 如果最早 > k，则没有可能的排序将其放置在删除的前缀内，因此输出 NO。 
8. 否则输出MAYBE。 

这对应于可能位置和截止点之间的重叠。 

### 为什么它有效

 排序顺序完全取决于等值组内的排列。 具有不同值的元素具有固定的相对顺序。 这意味着最爱的唯一不确定性来源是它在具有相同值的元素中的排名。 它的最终位置仅取决于在它之前放置了多少个等值元素。 该数字的范围可以从 0 到 equal − 1，独立于其他约束，因此收藏夹的位置跨越连续的区间 [greater + 1,greater + equal]。 在这个区间之外的任何位置都是不可能的，而在这个区间内的每个位置都可以通过适当的决胜来实现。 这使得与 k 的比较完整且准确。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, f, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    x = a[f - 1]
    
    greater = 0
    equal = 0
    
    for v in a:
        if v > x:
            greater += 1
        elif v == x:
            equal += 1
    
    earliest = greater + 1
    latest = greater + equal
    
    if latest <= k:
        print("YES")
    elif earliest > k:
        print("NO")
    else:
        print("MAYBE")
```该实现直接反映了派生的间隔逻辑。 唯一微妙的一点是索引：最喜欢的索引在输入中是从 1 开始的，因此在访问数组时必须将其转换为从 0 开始。 由于 n 很小，因此每个测试用例都会重新计算计数。 

决策逻辑完全避免了排序，这是不必要的，因为我们从不需要精确的排列，只需要最喜欢的立方体的排名间隔。

 ## 边缘情况

 所有值都相等的情况展示了全范围行为。 如果n = 4，k = 2，并且所有值都是7，则greater = 0且equal = 4，因此最早= 1，最晚= 4。根据决胜局，热门球队可以落在任何位置，因此可以将其删除或不删除，从而产生MAYBE。 该算法正确地捕获了这一点，因为间隔跨越了 k 的两侧。 

当最喜欢的值具有最大值时，greater = 0 且 equal = 1。间隔折叠到数组前面的单个位置。 如果 k ≥ 1，则始终将其删除，否则永远不会删除。 代码清楚地处理了这个问题，因为最早等于最新，消除了歧义。 

当 k 非常小时，只有元素严格强制进入前面的内容。 如果 Greater 已经超过 k，则无论平等群体行为如何，最爱的人都一定会被推到截止线之外，从而产生 NO。
