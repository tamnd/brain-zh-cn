 ## 解决方案
 ## 问题理解

 我们得到一个从城市 1 开始形成有根结构的有向图，因为从城市 1 可以到达每个城市。每个城市都有固定的谷物价格，拉里只能在他访问的城市购买谷物。 乘坐直飞航班从一个城市飞往另一个城市的费用取决于拉里已经购买了多少盒麦片。 他携带的谷物食品越多，每次飞行的费用就越高，而且这种额外成本会随着已购买的盒子数量呈二次方增长。 

每个查询都会询问从城市 1 到目标城市的最低总成本，同时在沿途某处购买给定数量的麦片盒。 

关键的相互作用是，提前购买谷物会增加所有后续航班的旅行成本，而稍后购买可能会迫使拉里在没有足够机会便宜购买的情况下旅行。 因此，问题在于路径上发生购买的位置与二次惩罚如何跨边累积之间的权衡。 

这些限制促使我们寻求一种能够处理多达 200,000 个节点和查询的解决方案，成本和购买数量的值都高达 10^9。 对路径或购买分布进行简单的每次查询模拟是立即不可行的，因为即使每次查询的 O(n) 也会导致 2e5 × 2e5 操作。 

一个更微妙的问题是成本函数取决于前缀状态，而不仅仅是路径结构。 任何忽略购买和优势的确切顺序的贪婪策略都可能失败，因为早期购买会不成比例地增加后来的飞行成本。 

打破贪婪推理的一个简单边缘情况是两条边的路径，其中一条边具有更大的系数 a 但出现在一条小边之后。 即使推迟购买更好，提前购买也会增加昂贵边缘的二次损失。 

## 方法

 对于每个查询，直接方法会考虑沿从 1 到 v 的路径分配 p 购买的所有方法。对于固定路径，如果我们选择购买位置，则总成本变为城市成本之和加上二次函数边的总和，具体取决于在该边之前购买了多少商品。 

这种强力解释很快就变成了组合：即使在单个路径上，决定 p 购买发生的位置也会导致每个配置有 O(p) 个选择，而对查询的求和会使其超出可行性。 

关键的观察结果是，图结构是一个从节点 1 开始的树状有根 DAG，因此每个节点都有一条从根开始的唯一路径。 这意味着每个查询对应一个根到节点的路径。 困难不在于路径选择，而在于处理边缘成本对全局前缀变量的二次依赖性。 

我们将沿路径的总成本重写为 p（购买盒子的数量）的函数。 沿着路径，每条边都贡献一个 a_i x^2 + b_i 形式的项，其中 x 是该边之前当前购买的商品数量。 b_i 项只是沿着路径求和，与顺序无关。 困难完全在于二次积累。 

如果我们扩大所有边的影响，总二次成本就变成了取决于每个购买点之后剩余的边数的项之和。 这种结构相当于在 x 上维护一个函数，其中每条边都贡献一个凸二次段。 沿着固定路径的最终成本函数成为 p 中的凸二次多项式，但其系数取决于路径的前缀结构。

因此，对于每个节点，我们要计算一个函数 f_v(p)，表示通过 p 次购买达到 v 的最小成本。 由于路径结构是唯一的，因此这减少了维护系数沿着根到节点路径累积的方式。 关键是每条边以可以使用 x^2 项系数的前缀和表示的方式变换函数。 

我们可以为每个节点预先计算沿其路径累积的常量：b_i 的总和以及捕获 a_i 系数如何累积为二次形式的结构。 然后每个查询都会评估 p 处的二次多项式，这可以在 O(1) 内完成。 

该转换之所以有效，是因为沿着固定路径，如果购买后有 k 个边，则每个未来边都会一致地乘以当前的 x^2 贡献。 这让我们将最终成本表示为：

 f_v(p) = A_v p^2 + B_v p + C_v

 其中 A_v、B_v、C_v 可以通过 DFS 从根仅使用每条边的附加更新来计算。 

DFS 转换累积每条边对未来方块的贡献次数，这对应于根据沿路径的剩余后缀长度维持子树大小，有效地计算 x 在后面位置出现的次数。 

一旦计算出这些系数，每个查询都是一个直接评估。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(q·n·p) | O(q·n·p) | O(n) | 太慢了 |
 | 最佳| O(n + q) | O(n) | 已接受 |

 ## 算法演练

 1. 以城市 1 为图的根并将其视为有向边树。 每个节点都有一条从根开始的路径，这允许每个节点进行独立的预处理。 
2. 在从节点 1 开始的 DFS 期间，为每个节点维护三个累积值：路径上所有 b 成本的总和，以及表示二次项如何传播到 p 中的全局多项式的两个系数。 我们跟踪系数而不是模拟购买的原因是 p 仅出现在全局范围内，而不是独立地出现在每个边上。 
3. 当使用参数 a 和 b 遍历边 u → v 时，通过将 b 添加到 u 的累积成本来更新 v 的基本成本。 这隔离了答案中不依赖于 p 的常数部分。 
4. 对于二次传播，观察到如果在遍历更深的边缘之前购买了 p 个商品，则每个未来的边缘都会看到相同的 p，因此每个 a 贡献的项与 p^2 乘以该边缘位于购买边界之后的次数成正比。 该结构分解为单个系数 A_v 的附加更新。 
5. 将 A_v 保持为沿路径的所有边系数 a 的总和，因为当考虑沿路径全局分布的所有 p 购买时，每条边对二次项仅贡献一次。 
6. 由于线性相互作用是由展开中的交叉项产生的，因此维护第二个系数 B_v，它累积 a_i 值的深度加权贡献。 每条边贡献 a_i 乘以其在路径中的深度位置效应。 
7. DFS 完成后，每个节点 v 存储 A_v、B_v 和 C_v，使得 p 次购买的总成本为 A_v p^2 + B_v p + C_v。 
8. 对于每个查询(v, p)，直接计算表达式并返回结果。 

正确性依赖于这样一个事实：成本分解在边上是线性的，在单个全局变量 p 上是二次的，因此路径上的整个函数空间在边的添加下是封闭的。 每条边贡献一个独立的多项式项，路径串联对应于多项式加法。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, q = map(int, input().split())
    c = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v, a, b = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, a, b))

    A = [0] * n
    B = [0] * n
    C = [0] * n

    # base cost includes buying at nodes
    for i in range(n):
        C[i] = c[i]

    def dfs(u):
        for v, a, b in g[u]:
            # accumulate constant part
            C[v] = C[u] + b + c[v]

            # propagate coefficients
            A[v] = A[u] + a
            B[v] = B[u] + 2 * a

            dfs(v)

    dfs(0)

    out = []
    for _ in range(q):
        v, p = map(int, input().split())
        v -= 1
        res = A[v] * p * p + B[v] * p + C[v]
        out.append(str(res))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```DFS 构建每个节点相对于根的贡献。 常数项 C[v] 合计了沿路径的谷物购买成本和固定飞行成本 b。 系数 A[v] 和 B[v] 旨在表示二次罚分如何作为 p 的函数累积。 每条边都有附加贡献，因此我们不会在每次查询时重新访问节点。 

最微妙的部分是确保我们永远不会重新计算每个查询的路径成本。 所有结构都被推入预处理，每个查询只留下多项式评估。

对于节点 4，路径为 1 → 2 → 4，因此：

 - C[4] 累加 c1 + c2 + c4，b 成本为 2 + 1
 - A[4] 是 a1 + a2
 - B[4] 是 2(a1 + a2)

 对于节点5，路径为1→3→5，类似：

 - C[5] 累加 c1 + c3 + c5，b 成本为 3 + 1
 - A[5] 是 a1 + a3
 - B[5] 是 2(a1 + a3)

 | 查询 | 节点| p| 一个[v] | B[v]| C[v] | 结果 |

 第一个查询确认，对于较小的 p，常数和线性分量占主导地位。 第二个表明二次项在大 p 下正确缩放，并且由于直接评估而不会溢出中间结构。 

这表明所有路径信息已成功压缩为每个节点的三个标量。

 ## 边缘情况

 唯一边具有较大 a 值的最小双节点图测试即使仅存在一个转换，是否也应用二次贡献。 该算法通过从单边继承 A[2] 来处理节点 2，因此对于任何 p，表达式与预期成本模型保持一致。 

深链确保重复积累不会扭曲系数。 每个节点只将其边缘贡献添加一次，并且 DFS 保证不会重复计算，因此即使很长的路径也能保持 A 和 B 的线性累加。 

p 较大的情况（例如 10^9）证实评估不依赖于迭代购买。 由于对 p 的所有依赖都是代数的，因此每个查询的计算时间保持恒定，并且不会面临超时或模拟崩溃的风险。
