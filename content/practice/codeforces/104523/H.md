 ## 解决方案
 ## 问题理解

 游乐园是一棵树，其中每个节点代表一个游乐设施。 首次参观游乐设施可提供固定的享受价值，但前提是该游乐设施当天可以运营。 每个游乐设施都有一个定期时间表：仅在其周期的倍数的日子开放。 如果游乐设施在开始日关闭，则该节点也会有效地阻止通过其事件边缘的遍历，因此任何探索都无法通过它。 除此之外，每个查询还会强制永久关闭一个选定的游乐设施。 

每个查询都要求从给定节点开始，沿着开放节点在树中移动，同时在首次访问时对每个可到达的骑行进行一次计数，但前提是它在起始日开放，而不是强制关闭的节点。 

关键的相互作用是两个约束之间的相互作用。 树结构决定了哪些节点是可达的，而起始日的模块化条件决定了哪些节点实际上是可用的。 强制删除为每个查询在树中添加动态剪切。 

这些约束清楚地表明，任何解决方案都必须接近每个查询的线性或使用大量预处理。 对于多达 100000 个节点和查询，重新计算可达性或每次查询遍历树是不可能的。 即使每个查询的 O(n) 也会导致 10^10 次操作，这太大了。 该解决方案必须预先计算结构，允许在节点删除下进行快速组件查询，并根据可分性条件快速过滤有效节点。 

一种简单的方法是，对于每个查询，删除禁止的节点，然后从起始节点执行 DFS 或 BFS，跳过打开条件失败的任何节点。 这是正确的，但它每次都会从头开始重新计算连接性，并重复扫描树的大部分。 

开放约束产生了一个微妙的陷阱。 如果错误地假设树结构单独确定了静态连接组件，那么他们将过多计算在开始日关闭的节点。 另一种失败模式是忘记关闭的节点还会阻止遍历，而不仅仅是评分。 

## 方法

 暴力方法独立处理每个查询。 我们删除禁止节点，然后从起始节点开始遍历。 遍历时，我们只输入周期除以查询日的节点。 每个被访问的节点贡献一次它的值。 

这是可行的，因为树是静态的，遍历自然避免了循环。 然而，在最坏的情况下，每个查询都可能遍历几乎整棵树。 对于 100000 个节点和 100000 个查询，这变成了 10^10 次操作，这远远超出了限制。 

关键的观察是，在删除单个节点的情况下，树中的可达性结构可以使用子树分解来描述。 删除一个节点会将树分成相对于该节点的最多三个相关部分：其子树中的有根表示的节点、其上方的节点以及树的其余部分，其中每个部分都可以使用预先计算的排序（例如欧拉游览间隔）进行推理。 

第二个观察结果是，可分性约束仅取决于查询日期和节点值，而不取决于树结构。 这意味着我们可以将结构可达性与激活过滤分开。 如果我们能够在删除节点后快速计算连接组件中的值之和，然后减去那些不满足整除条件的节点，我们就可以有效地回答每个查询。

这导致了树上离线预处理和对 b 值的快速整除分组的经典组合。 我们对树进行预处理，以便对于任何节点 z，我们可以使用子树和和父子关系在 O(log n) 或 O(1) 中计算其移除的贡献。 另外，我们预先计算由 b 索引的节点组，以便对于给定的 y 天，我们可以确定哪些节点处于活动状态。

 ## 算法演练

 我们以节点 1 为树的根并计算欧拉之旅，因此每个子树都对应于一个连续的线段。 我们还计算欧拉阶上的前缀和，从而允许快速子树和查询。 

我们还为每个节点计算其父节点和深度，以便删除节点将树拆分为一组不相交的组件，这些组件对应于其父节点或其子子树。 

我们还为每个节点预先计算其子树中所有 a 值的总和。 

接下来，我们预处理按 b 值分组的节点。 对于每个可能的周期值 b，我们维护具有该周期的节点列表。 

对于每个查询 (x, y, z)，我们按如下方式进行。 

1. 通过验证 y % b[x] == 0 来检查节点 x 本身在 y 是否可用。如果不可用，则答案从 0 开始，因为我们无法访问通过有效起始条件无法访问的任何节点。 
2. 计算如果删除 z，则从 x 可到达的连接组件中的所有节点的总和。 这是通过使用子树求和和祖先检查来完成的：如果 z 不在 x 的子树中，则删除不会影响可达性，因此该组件是以 x 为根的完整树。 如果 z 位于路径中，我们减去相应的受影响子树贡献。 
3. 从该结构和中减去节点 z（如果包含）。 
4.最后，删除b值不能整除y的所有节点。 我们不检查每个节点，而是使用预先计算的列表：对于 y 的每个除数 d，我们迭代 b = d 的节点，并使用欧拉游览段和累积它们的贡献，确保我们只计算结构上可达的节点。 

最终答案是仅限于满足可分性约束的节点的总可达结构和。 

为什么这样做有效是因为树的连通性与日过滤无关，而日过滤与遍历顺序无关。 任何有效路径仅包括满足这两个条件的节点，因此结构组件和有效节点的交集就足够了。 由于这两个集合在包含节点的情况下都是封闭的，因此正确地对它们的交集求和就可以计算出总的乐趣。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

parent = [-1] * n
depth = [0] * n
tin = [0] * n
tout = [0] * n
order = []
sub = [0] * n

def dfs(u, p):
    parent[u] = p
    tin[u] = len(order)
    order.append(u)
    sub[u] = a[u]
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        dfs(v, u)
        sub[u] += sub[v]
    tout[u] = len(order) - 1

dfs(0, -1)

def is_ancestor(u, v):
    return tin[u] <= tin[v] <= tout[u]

div_groups = {}
for i in range(n):
    div_groups.setdefault(b[i], []).append(i)

def component_sum(x, blocked):
    if x == blocked:
        return 0
    if not is_ancestor(blocked, x):
        return sub[x]
    for v in g[blocked]:
        if v == parent[blocked]:
            continue
        if is_ancestor(v, x):
            return sub[x] - sub[v]
    return sub[x]

def collect_divisors(x):
    res = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            res.append(i)
            if i * i != x:
                res.append(x // i)
        i += 1
    return res

for _ in range(q):
    x, y, z = map(int, input().split())
    x -= 1
    z -= 1

    if y % b[x] != 0:
        print(0)
        continue

    base = component_sum(x, z)

    total = 0
    for d in collect_divisors(y):
        if d in div_groups:
            for u in div_groups[d]:
                # check if u is in component of x after removing z
                if u == z:
                    continue
                if is_ancestor(u, x) or is_ancestor(x, u):
                    total += a[u]

    print(total)
```该解决方案使用欧拉游览将子树关系转变为区间检查。 component_sum 函数计算当起始节点位于其子树内部时删除节点如何分裂树。 可整除性过滤是通过迭代查询日的除数来处理的，因为只有其周期整除该日的节点才能做出贡献。 

一个微妙的实现细节是祖先检查，它在删除后取代了显式连接检查。 如果没有它，断开连接的分支中的节点可能会被错误地包含在内。 另一个关键细节是处理被阻塞的节点恰好是起始节点的情况，这会立即使所有遍历无效。 

## 工作示例

 考虑样本输入。 

对于第 123 天从节点 1 开始且节点 2 被阻止的查询，如果节点 1 的周期整除 123，则节点 1 有效。如果不是，答案立即为零。 否则，我们计算从节点 1（不包括节点 2）可到达的组件，然后对该组件中周期除以 123 的所有节点求和。 

对于第 124 天从节点 2 开始且节点 1 被阻止的另一个查询，我们首先验证节点 2 是否处于活动状态。 然后我们计算删除节点 1 后的连通区域，节点 1 将树的一部分分开。 然后，我们仅包含 b 值除以 124 的节点，并累加它们的 a 值。 

简化子树的跟踪表：

 | 步骤| x| z | 活跃节点| 组件总和|
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 1 | {2,3} | 5 |
 | 2 | 7 | 1 | {} | 0 |

 这演示了结构去除和可分性过滤如何独立相互作用。

 ## 边缘情况

 一个关键的边缘情况是当被阻止的节点恰好位于从 x 到许多可到达节点的路径上时。 在这种情况下，不进行分割的朴素子树求和将错误地包含块后面的节点。 基于欧拉的祖先检查可确保正确排除分离组件中的任何节点。 

当 x 本身被阻塞时，会出现另一种边缘情况。 该算法立即返回零，因为从删除的起始节点开始不可能进行遍历，这与从该点开始无法访问或扩展任何游乐设施的事实相匹配。
