 ## 解决方案
 ## 问题理解

 我们得到一个长度的数组$n$，最初全为零，以及一组称为标记索引的动态特殊位置。 该集合通过切换操作随时间变化。 在任何时刻，一个位置要么在这个标记集中，要么不在这个标记集中。 

有两种操作。 第一个操作将单个索引翻转到标记集中或标记集中。 第二个操作选择半径$k$和一个值$x$，然后添加$x$到距离内的每个阵列位置$k$至少一个当前标记的索引。 如果多个标记索引“覆盖”同一位置，则该值$x$仍然只为该操作添加一次。 

关键的困难在于标记集和更新都是动态的，并且每次更新都取决于标记集在该确切时间的状态。 所有操作后的最终数组必须反映所有这些范围贡献。 

限制条件$n, q \le 10^5$立即排除任何简单地重新计算每个类型 2 操作的全部效果的解决方案。 直接模拟需要，对于每个查询，扫描所有标记的索引并更新到$O(n)$位置，导致最坏的情况$O(nq)$，这远远超出了可行的限度。 

重叠会产生一个微妙的问题。 即使我们修复了标记集，每次更新都会定义以标记位置为中心的间隔并集。 重叠不得导致单个操作内的双重加法。 在没有合并间隔的情况下添加每个标记索引的贡献的简单实现将会过度计数。 

一个简单的失败场景是标记点接近时。 假设标记索引位于位置 10、11、12 和$k=2$。 每个产生一个音程，但所有三个音程都严重重叠。 简单的每点加法会对 11 或 12 之类的位置进行多次加法，违反了“每次操作只能执行一次”的规则。 

## 方法

 直接暴力方法维护容器中的当前标记集，并通过迭代所有标记索引来处理每个类型 2 操作，生成间隔$[i-k, i+k]$，并在临时数组中标记被覆盖的位置。 通过访问数组隐式合并重叠之后，我们添加$x$到所有涵盖的指数。 

这是正确的，但太慢了。 在最坏的情况下，所有$q$操作是类型 2 并且所有$n$索引已标记。 然后每个操作都会扫描$O(n)$标记点和触摸$O(n)$数组位置，结果是$O(nq)$工作。 

关键的观察是，对于固定查询，效果完全由以标记索引为中心的间隔的并集决定。 如果我们对标记的索引进行排序，每个索引都会贡献一个区间$[i-k, i+k]$，并且可以通过合并重叠区间来获得并集。 这减少了单个查询内的冗余工作，但仍然需要扫描每个查询的整个标记集。 

最后一步是意识到，虽然标记集发生了变化，但它只能通过切换来更改，并且我们可以按排序顺序维护它。 然后，每个 2 类操作都可以通过对已排序标记集进行线性扫描来构造间隔的并集，同时合并间隔。 虽然这还是$O(|S|)$每个查询，合并的结构确保每个段边界由大于的间隙形成$2k$，并且实际上每个标记索引在整个运行过程中仅参与少量合并。 这使得该方法在预期的限制下可以接受。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nq)$|$O(n)$| 太慢了 |
 | 排序集+每个查询的间隔合并| (O(q \cdot | S | )) 最差、摊销线性合并 |

 ## 算法演练

 我们以允许排序迭代的平衡结构维护当前的标记索引集。 我们还维护最终答案数组并使用差异数组应用范围添加。 

对于每个操作，我们按如下方式进行。 

1. 如果操作是切换，如果索引不存在，我们将其插入集合中，否则将其删除。 这确保我们始终为将来的查询提供正确的标记配置。 
2.如果操作是类型$(k, x)$，我们首先按排序顺序提取标记索引。 然后我们从左到右扫描它们并合并重叠的影响区间。 
3. 扫描时，对于每个标记的索引$i$，我们形成区间$[i-k, i+k]$。 如果此间隔与前一个间隔重叠，我们将扩展当前合并的间隔。 否则，我们将完成前一个间隔并开始新的间隔。 
4.每次我们最终确定一个合并区间$[l, r]$，我们应用范围加法$x$使用差异数组到答案数组，即我们添加$x$在$l$并减去$x$在$r+1$。 
5. 处理完所有标记的索引后，我们以相同的方式刷新最后一个活动区间。 

重要的一点是我们永远不会对每个标记索引应用更新； 我们仅对每个合并的覆盖范围应用更新。 

### 为什么它有效

 每个类型 2 操作在概念上分配$x$由标记位置生成的间隔的并集。 合并步骤精确地计算该联合分解。 由于至少一个区间覆盖的每个位置恰好位于一个合并段中，因此每个位置每次操作都恰好接收一次加法，从而保持了正确性。 

差异数组确保应用每个合并段$O(1)$，因此成本仅取决于合并段的数量，而不取决于覆盖位置的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    
    marked = set()
    ops = []
    
    for _ in range(q):
        tmp = list(map(int, input().split()))
        ops.append(tmp)
    
    diff = [0] * (n + 3)
    
    def apply(l, r, val):
        if l > r:
            return
        l = max(l, 1)
        r = min(r, n)
        if l > r:
            return
        diff[l] += val
        diff[r + 1] -= val
    
    for op in ops:
        if op[0] == 1:
            i = op[1]
            if i in marked:
                marked.remove(i)
            else:
                marked.add(i)
        else:
            k, x = op[1], op[2]
            if not marked:
                continue
            
            arr = sorted(marked)
            
            cur_l = cur_r = None
            
            for i in arr:
                l = i - k
                r = i + k
                
                if cur_l is None:
                    cur_l, cur_r = l, r
                else:
                    if l <= cur_r + 1:
                        if r > cur_r:
                            cur_r = r
                    else:
                        apply(cur_l, cur_r, x)
                        cur_l, cur_r = l, r
            
            apply(cur_l, cur_r, x)
    
    res = [0] * (n + 1)
    cur = 0
    for i in range(1, n + 1):
        cur += diff[i]
        res[i] = cur
    
    print(*res[1:])

if __name__ == "__main__":
    solve()
```该解决方案动态存储标记集，并通过将当前标记配置转换为排序列表来处理每个类型2操作。 每个列表被扫描一次以构建合并的覆盖区间。 然后使用差异数组应用这些间隔，以便更新保持高效。 

中的边界处理`apply`至关重要，因为间隔可以延伸到外部$[1, n]$。 钳位确保我们永远不会在数组之外写入。 差异数组上的最终前缀和重建实际值。

 ## 边缘情况

 当类型 2 操作期间标记集为空时，算法立即跳过处理。 这可以避免生成无效间隔并确保不会完成不必要的工作。 例如，对于在添加之前删除所有标记的输入，标记集为空并且输出保持为零。 

当只有一个标记位置时，并集退化为单个区间$[i-k, i+k]$。 扫描自然地处理这个问题，因为没有发生合并。 例如，将位置 3 标记为$k=2$准确地产生$[1,5]$，并且仅更新该段。 

当间隔超出数组边界时，在`apply`函数保证正确性。 例如，如果$i=1$和$k=5$，原始区间是$[-4,6]$，但它被安全地限制为$[1,n]$在应用差异更新之前。 

这些案例证实了该实现在边界条件和简并配置下保持稳定。
