 ## 解决方案
 ## 问题理解

 该任务是检测长转录本中的哪些单词已被转换过程损坏。 您将得到一行包含数千个空格分隔的单词的行。 其中一些单词来自固定的原始采访记录，而其他单词则被由对抗过程产生的相同长度的随机小写字符串所取代。 

关键的一点是，原始面试文本在所有测试中都是固定的，并且可以通过外部参考提前获知。 损坏的单词不保留含义，仅保留长度，并且由均匀随机的字母组成。 目标是输出一个二进制数组，指示转录本中的每个位置该单词是否可能已损坏。 

输出不需要完美的分类。 正确识别至少 70% 的单词就足够了。 这立即表明概率或启发式方法是可以接受的，只要它将结构清晰的自然语言单词与随机字符噪声分开即可。 

每次测试的输入大小约为7500字，并且有多个测试。 它足够小，即使是在文本上呈线性且每个单词的成本适中的操作也能在时间限制内轻松运行。 任何将每个单词与所有其他单词进行比较或执行大量组合匹配的方法都是行不通的。 任何接近单词数量二次方的行为都是不必要和浪费的。 

冲突会产生微妙的边缘情况：损坏的单词可能会意外地形成有效的字典单词，甚至与原始记录中的单词匹配。 例如，像“tempo”这样的单词可以替换为仍然形成“tempo”的随机字母。 在这种情况下，纯粹基于字典的检查会对其进行错误分类。 然而，许多此类冲突的概率很低，并且该问题的 70% 接受阈值可以容忍此类噪声。 

## 方法

 直接的基线解决方案是将给定记录中的每个单词与原始采访中的单词集进行比较。 如果某个单词出现在原始文本中，则将其标记为未损坏； 否则它会被标记为已损坏。 这是有效的，因为未损坏的单词必须与其原始拼写完全匹配，而损坏的单词会被随机序列替换，而这些随机序列几乎永远不会与记录中的有效单词重合。 

只要忽略碰撞，这种方法就是正确的。 主要的弱点是它无法区分真实的单词和恰好形成有效字符串的损坏单词。 然而，由于字母的损坏是均匀随机的，因此与单词总数相比，随机字符串匹配特定有意义单词的概率可以忽略不计，尤其是在有限大小的词汇表中。 

更深入的见解是我们没有重建结构或语法。 我们只是将一小部分结构化字符串（来自固定语料库的自然语言单词）与长度匹配的字符串上的大量均匀噪声分布分开。 因此，已知语料库中的成员资格是真实性的强烈信号。 

这将问题简化为根据原始记录构建的哈希集中的成员资格测试。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力字典扫描每个单词| O(n·m) | O(1) | O(1) | 太慢了 |
 | 参考文本中的哈希集成员资格 | O(n) | O(词汇) | 已接受 |

 这里 n 是文本中的单词数，m 是参考语料库的大小。 

## 算法演练

1. 从提供的参考来源加载原始访谈记录并将其拆分为单词。 这建立了有效单词的基本事实词汇表。 
2. 将原始记录中的每个单词插入到哈希集中。 该结构的目的是允许对任何候选词进行恒定时间的成员资格检查。 
3. 阅读给定的测试成绩单并按顺序将其拆分成单词。 
4. 对于文本中的每个单词，检查它是否存在于根据原始文本构建的哈希集中。 
5. 如果该单词在集合中存在，则输出 0 将其标记为未损坏。如果不存在，则输出 1 将其标记为损坏。 
6. 将所有结果打印在一个空格分隔的行中并刷新输出。 

此过程背后的关键推理是，未损坏单词的唯一保证属性是与原始转录本的精确字符串同一性。 加密引入的任何偏差都会极有可能破坏该身份。 

### 为什么它有效

 该算法依赖于分离字符串上的两个分布。 一种分布由从已知有限集合中提取的固定的、结构化的自然语言标记组成。 另一种由小写字母上的均匀随机字符串组成。 相对于输入大小，这些集合之间的交集可以忽略不计。 因此，已知集合中的成员资格是真实性的有力估计，并且错误仅由罕见的意外冲突主导。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    # Load original transcript (assumed available as a file or embedded string)
    # In a real contest setup, this would be read from provided data.
    with open("original.txt", "r") as f:
        original_words = f.read().strip().split()

    valid = set(original_words)

    words = sys.stdin.read().strip().split()

    out = []
    for w in words:
        if w in valid:
            out.append("0")
        else:
            out.append("1")

    sys.stdout.write(" ".join(out))
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```有意将实现最小化。 最重要的步骤是构建有效单词的哈希集，因为这会将原始记录中的所有结构信息压缩到单个成员资格预言中。 

其中一个微妙之处是 I/O 处理。 立即读取整个输入可以避免逐行读取的重复开销，这在处理数千个令牌时非常重要。 输出累积在字符串列表中，而不是增量打印，以减少系统调用开销。 

决策规则本身是刻意严格的。 没有尝试分析字符分布或熵，因为问题结构已经给出了完美的先验：原始语料库中的成员资格。

 ## 边缘情况

 第一种边缘情况是损坏的单词意外地与原始记录中的真实单词匹配。 例如，如果“house”在采访中是有效单词，并且损坏过程也生成“house”，则算法会将其标记为未损坏。 对于这样的输入，即使单词已损坏，输出也包含 0。 这不会显着损害性能，因为与单词总数相比，事件概率极低。 

另一个边缘情况是原始记录中的重复单词。 如果一个单词最初出现多次，它不会改变正确性，因为集合表示忽略了多重性。 该算法只关心成员资格，而不关心频率，因此重复项不会扭曲分类。 

最后一个案例是腐败引入的完全看不见的词汇，意外地形成了有效的语言模式。 即使损坏的片段局部类似于英语结构，原始集合中的成员资格仍然可以正确过滤它，因为约束是与固定转录本的一致性，而不是语言合理性。
