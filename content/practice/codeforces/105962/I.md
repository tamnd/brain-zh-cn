 ## 解决方案
 ## 问题理解

 我们给出了一组问题，每个问题都由两个数字描述。 第一个数字是一个阈值要求：贝拉尔多只有当前光环至少达到该值才能解决该问题。 第二个数字是奖励：如果他解决了问题，他的光环就会增加相应数量。 他从初始光环值开始，可以选择任何解决问题的顺序，但每个问题最多可以使用一次。 

任务是在反复选择可解决的问题并应用其奖励后，确定他最终可以达到的最大光环。 

关键的困难在于解决一个问题会改变一系列可用的问题。 最初太难的问题可能会在以后变得可以解决，而早期选择错误的问题可能会阻碍以后获得更好的增长。 

这些约束最多允许 100,000 个问题，因此任何尝试所有排列或模拟所有子集的解决方案都是不可能的。 即使是每一步扫描所有剩余问题的二次模拟，在最坏的情况下也会导致大约 10^10 次操作，这远远超出了一秒的限制。 这立即排除了天真的按顺序贪婪或没有有效簿记的重复扫描策略。 

当一个问题提供大的奖励但要求很高，而较小的奖励问题则解锁对它的访问时，就会出现微妙的失败案例。 例如，如果我们从低光环开始并贪婪地选择最大的即时奖励，我们可能会错过稍后解锁更大收益的序列。 排序在全球范围内都很重要，而不是在本地。 

当所有可用问题最初需要比我们更多的光环时，就会出现另一种边缘情况。 在这种情况下，答案只是起始光环，因为不可能有进展。 

## 方法

 蛮力方法将模拟所有可能的解决问题的顺序。 从给定的光环中，我们检查每个未解决的问题，尝试当前可用的任何问题，在应用其奖励后递归，并跟踪最大结果。 这可以正确地对问题进行建模，因为它探索了所有有效的操作序列。 

然而，每一步的分支因子最多为 N，深度也最多为 N。这会导致在最坏的情况下出现大约 N 的阶乘行为，即使 N 小到 20，这也是完全不可行的，更不用说 100,000 了。 

关键的观察是，每一步的决策仅取决于当前可以承受的问题，而不是完整的历史记录。 在当前所有可解决的问题中，如果已经存在较高奖励选项，那么选择任何低奖励选项而不是较高奖励选项永远不会有好处。 原因是单调性：光环只会增加，所以一旦问题变得可用，它就一直可用直到解决。 

这表明了一个贪婪的过程：维护所有要求最多为当前光环的问题的集合，并始终在其中选择奖励最大的问题。 每个选择都会增加光环，可能会解锁新的问题。 这可以使用排序和最大堆有效地实现。 

我们首先按照所需的光环对问题进行排序。 然后，随着当前光环的增长，我们会扫过它们，将所有新解锁的问题推入由奖励键控的最大堆中。 每次我们获得最好的奖励时，我们都会增加光环并继续。 这确保了一旦高价值问题可以解决，我们就不会浪费任何机会去解决它。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N!) | O(N) | 太慢了 |
 | 最优（排序+堆）| O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

 我们维护两种结构：按所需光环排序的问题列表，以及包含当前可解决问题的奖励的最大堆。

1.将所有问题按照其要求值Ai以非降序排列。 这使我们能够知道随着光环的增加，问题会以什么顺序出现。 
2. 初始化排序列表上的指针并将当前光环设置为 K。同时初始化一个空的最大堆。 
3. 当下一个问题的要求最多是当前光环时，将指针向前移动，并将其奖励推入堆中。 此步骤收集所有新出现的问题。 
4. 如果此时堆为空，则意味着当前光环无法解决剩余问题，因此进程停止。 
5. 否则，从堆中提取奖励最大的问题，并将其奖励添加到当前光环中。 这代表选择最有利可图的可用行动。 
6. 重复步骤 3 至 5，直到无法再继续为止。 

我们总是在选择之前扩展堆的原因是解决一个问题可能会解锁许多其他问题，并且我们希望确保在做出选择之前考虑所有当前可达的选项。 

### 为什么它有效

 在任何时刻，算法都保持不变，即堆恰好包含所有未解决问题的奖励，其要求最多是当前光环。 由于光环只会增加，所以一旦问题变得合格，它就永远不会变得不合格。 因此，我们绝不会错过任何可能的行动。 

在目前所有可用的行动中，选择最大奖励是安全的，因为任何较小的奖励选择都会让我们之后的光环较低或相等，这无法比较高奖励选择解决更多问题。 这种单调性确保局部最优选择不会阻碍未来的机会。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, k = map(int, input().split())
    problems = []
    for _ in range(n):
        a, b = map(int, input().split())
        problems.append((a, b))
    
    problems.sort()
    
    i = 0
    aura = k
    heap = []
    
    while True:
        while i < n and problems[i][0] <= aura:
            heapq.heappush(heap, -problems[i][1])
            i += 1
        
        if not heap:
            break
        
        aura += -heapq.heappop(heap)
    
    print(aura)

if __name__ == "__main__":
    solve()
```代码首先对问题进行排序，以便我们可以随着光环的增长逐步激活它们。 指针`i`确保每个问题都被准确地推入堆一次，从而在排序后保持预处理的线性。 

堆存储负值以使用 Python 的最小堆实现模拟最大堆。 每次迭代，我们都会确保在选择最佳奖励之前插入所有当前可解决的问题。 

一个常见的实施陷阱是在增加光环后忘记重新检查新解锁的问题。 这就是外循环在扩展堆和消耗堆之间交替的原因。

 ## 边缘情况

 关键的边缘情况是最初无法解决问题的情况。 对于输入：```
3 1
10 5
20 10
30 100
```该算法对所有问题进行排序，但从不向堆中插入任何内容，因为指针永远不会前进。 堆立即保持为空，因此循环终止并输出 1，这是正确的，因为无法执行任何操作。 

另一种情况是当解锁发生在链中时。 例如：```
3 1
1 2
3 3
5 10
```在光环 1 时，只有第一个问题进入堆并被采取，将光环增加到 3。这会立即解锁第二个问题，然后被采取，解锁第三个问题。 该算法自然地处理这个问题，因为每次增益后都会重复堆扩展，确保每个阶段都考虑所有新可达的问题。
