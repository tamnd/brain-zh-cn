 ## 解决方案
 ## 问题理解

 我们有一堆石头和两名交替轮流的玩家，从伊文斯开始。 每回合，当前玩家必须从堆中取出一颗或两颗石子。 最终拿走最后一块石头的玩家就输了，因此我们的目标是避免成为最后一步将石头堆清空的人。 

输入只是石头的初始数量。 输出是在最佳发挥下能够取得胜利的玩家的名字。 

这些约束允许棋子数量最多为 1e9，这立即排除了对游戏状态的任何模拟。 任何尝试探索从 1 到 n 的所有位置或在整个范围内使用动态规划的方法在时间和内存上都太慢。 该解决方案必须将游戏分解为每个输入的恒定时间决策。 

误读此游戏的一个常见陷阱是忘记失败条件适用于拿走最后一颗棋子的玩家，而不是拿走最后一颗棋子获胜的通常惯例。 单个反转会翻转所有基本情况。 例如，当 n = 1 时，Yvens 被迫立即拿走最后一块石头并输掉，因此 Esteche 获胜。 当 n = 2 时，伊文斯可以拿走两颗棋子，但也立即输掉。 当 n = 3 时，伊文斯拿走一颗或两颗棋子，在两种情况下都给埃斯特切留下失败的位置，因此伊文斯获胜。 任何不正确的基本情况假设都可能会破坏以后的周期性推理。 

另一个微妙的情况是小值，两种移动都可用，但会立即导致损失。 例如，n = 2 就特别具有欺骗性，因为两种合法的走法都会立即结束游戏，这意味着第一个玩家尽管有两种选择，却没有获胜的走法。 

## 方法

 如果我们尝试直接从规则中推理，我们可以将每个石子数量视为一种游戏状态，玩家移动时要么获胜，要么失败。 从状态 n，玩家可以进入 n-1 或 n-2，如果这些转换中至少有一个导致对手输掉状态，则当前状态为获胜。 暴力方法将使用动态规划计算从 1 到 n 的所有值的分类。 

这很有效，因为游戏具有最佳的子结构：一个位置的结果仅取决于较小的位置。 然而，强力方法需要 O(n) 个状态和每个状态的恒定转换，因此需要线性时间和内存。 当 n 达到 1e9 时，迭代所有状态是不可能的。 

关键的观察结果是，复发很快就会稳定为重复模式。 计算小值表明：

 n = 1 失败

 n = 2 失败

 n = 3 获胜

 n = 4 获胜

 n = 5 正在失败

 n = 6 失败

 n = 7 获胜

 n = 8 获胜

 该模式每 4 个状态重复一次：失败、失败、获胜、获胜。 发生这种情况是因为该游戏相当于减法游戏的变体，其中移动从 {1, 2} 中删除元素，并且失败条件相对于正常 Nim 终止相反。 该结构强制位置同余模 4 表现相同。 

一旦认识到这种周期性，问题就简化为计算 n mod 4 并对余数进行分类。

 | 暴力DP | O(n) | O(n) | 太慢了 |
 | 模块化模式| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将博弈简化为小残数上的行为，然后使用周期性将其扩展到所有 n。

1. 计算 r = n mod 4。这将整个状态空间压缩为四个等价类之一，因为转换结构每四个值重复一次。 
2. 如果 r 为 1 或 2，则玩家移动的位置正在丢失。 这对应于任何举动都会立即给对手带来获胜配置的情况。 
3. 如果r为0或3，则该位置是玩家移动的获胜位置。 在这些情况下，至少存在一招迫使对手陷入失败的局面。 
4. 由于Yvens总是先手，如果起始位置获胜则输出“Yvens”，否则输出“Esteche”。 

### 为什么它有效

 不变量是位置 n 的结果仅取决于 n mod 4。通过检查获胜状态的递推关系 W(n) = 不是 W(n−1) 或不是 W(n−2)，在前几个基本情况之后产生周期序列来证明这一点是合理的。 一旦循环稳定，每一步都会保留移动四次的相同结构。 因此，同一残基类别中的所有位置都具有相同的赢或输状态，使得模块化分类对于所有 n 都是精确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())

r = n % 4

# losing positions are 1 and 2 modulo 4
if r == 1 or r == 2:
    print("Esteche")
else:
    print("Yvens")
```该代码读取初始堆大小并将其减少到模 4 的余数。该余数直接决定当前玩家是否强制获胜。 关键的实现细节是分类对于所有 n 都是完全对称的，因此不需要循环或预计算。 

在观察基本模式后，残基到结果的映射被硬编码。 该决定是在恒定时间内做出的。

 从 n = 1 开始，伊文斯必须拿走最后一块石头并立即失败，因此埃斯特切获胜。 

### 示例 2：n = 7

 我们计算 r = 7 mod 4 = 3。 

| n | r | 职位类型| 结果|
 | ---| ---| ---| ---|
 | 7 | 3 | 获胜| 伊文斯 |

 从 n = 7 开始，Yvens 可以移动到 6 或 5。6 和 5 都是失败位置，因此任何移动都会使 Esteche 处于失败状态，从而确认 Yvens 获胜。 

这两种情况显示了两个连续值组中获胜和失败块的交替。

 ## 边缘情况

 对于 n = 1，我们有 r = 1。算法将其分类为失败，因此打印 Esteche。 这与伊文斯拿下最后一块石头并立即输掉的强制走法相匹配。 

当 n = 2 时，r = 2。两种可能的走法都会立即结束游戏，因此起始玩家无法避免拿走最后一颗棋子。 模块化规则仍然正确地将其归类为失败。 

当 n = 4 时，r = 0。该算法预测获胜位置。 事实上，Yvens 可以移动到 n = 3，这对对手来说是失败的状态，无论 Esteche 的反应如何，都能确保强行获胜。 

对于 n = 5，r = 1。算法将其标记为失败。 任何从 5 到 4 或 3 的移动都会导致下一个玩家获胜，因此伊文斯在最佳发挥下无法避免失败。
