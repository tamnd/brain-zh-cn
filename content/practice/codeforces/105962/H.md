 ## 解决方案
 ## 问题理解

 我们得到了队列的一系列快照。 每个快照都是当前在某个时间队列中的所有学生的完整有序列表，并且这些快照按时间顺序显示。 随着时间的推移，学生只会进入队列，一旦他们进入，他们就不会改变与已经在队列中的人的相对顺序。 唯一的例外是，当学生进入时，他们可以加入队列中的任何位置，不一定是最后。 

任务是确定每个学生是否有证据表明他们曾以非最后的位置进入队列。 如果学生第一次出现时始终排在当前队列的末尾，或者根本没有出现在快照中，则视为有效。 否则，如果在某个时刻它们出现在快照中的位置迫使它们插入现有队列中间的某个位置，则它们会被标记为已插队。 

限制很大：总共可以有 100,000 个快照，并且最多可以有 100,000 个不同的学生。 这立即排除了任何比较每对快照或尝试使用简单列表操作模拟插入的解决方案。 任何元素总数呈二次方的方法都会太慢，因为即使 10^5 的平方也已经是 10^10 次运算了。 

一个微妙的问题源于这样一个事实：我们永远不会直接看到插入事件，只能看到多次插入后的最终状态。 这意味着我们不能依赖条目的时间戳，只能依赖连续快照之间的一致性。 

一个经常打破天真的想法的边缘情况是当学生第一次出现时。 例如，如果第一个快照是`[3, 5, 1]`，它可能看起来像学生 1“切入”，但实际上我们没有先前的状态，因此无法证明存在不当行为。 任何正确的解决方案都必须将第一个快照视为基本状态，而不进行任何指责。 

另一个边缘情况是学生从未出现在任何快照中。 它们必须输出为 0，因为没有证据表明它们曾经进入队列。 

## 方法

 一个蛮力的想法是尝试重建队列演化的整个历史。 人们可以想象模拟快照之间所有可能的插入点并检查一致性。 另一种幼稚的尝试是将每个快照与前一个快照进行比较，并尝试使用扫描或插入列表的数组操作来检测哪些元素插入到何处。 

这些方法的问题在于，插入到 Python 列表的中间的时间复杂度为 O(n)，并且对于跨快照最多 10^5 个元素执行此操作会导致最坏情况的 O(n^2) 行为。 类似地，从头开始重新计算每个快照的位置会导致重复扫描已处理的结构。 

关键的观察是我们实际上并不需要重建所有有效的历史。 我们只需要检测维护的“当前队列状态”和每个传入快照之间的不一致。 由于学生一旦出现就不会改变相对顺序，因此队列的现有部分就像一个稳定的主干。 这个主干和下一个快照之间的任何不匹配只能通过在当前指针位置之前插入一个新学生来解释，这正是“剪线”的条件。 

这将问题转化为两个有序序列之间的受控合并：维护的队列和下一个快照。 每当我们看到不匹配时，快照中的元素必须重新插入到该位置，如果该位置不在当前队列的末尾，则立即成为剪切的证据。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力重建| O(N²) | O(N) | 太慢了 |
 | 带有链接结构的增量合并 | O(N) | O(N) | 已接受 |

 ## 算法演练

 我们将当前已知的队列维护为双向链表，因为我们需要在常数时间内向中间插入元素。 我们还保留一个指针，在处理每个快照时遍历此列表。 

我们还维护一个布尔数组`bad[i]`表明是否是学生`i`已被证明已断线。 

1. 从一个空链表开始，所有学生都标记为不错。 
2. 处理第一个快照，将其所有元素按顺序插入到链表中。 这里没有学生被标记为差，因为没有先前的状态可供比较。 
3.对于每个后续快照，设置一个指针`cur`到当前链表的头部并从左到右扫描快照。 
4. 对于每个学生`x`在快照中，将其与`cur`：

如果`cur`存在并且`cur.value == x`，那么两个表示都同意这个立场，所以我们前进`cur`向前。 

如果它们不同，那么`x`必须是出现在当前队列位置之前的新插入的学生`cur`。 在这种情况下，我们标记`x`一样糟糕并将其插入之前`cur`在链接列表中。 我们不动`cur`，因为当前骨干位置尚未匹配。 
5.如果`cur`变为空，这意味着快照的其余部分完全由新学生组成，因此我们将它们附加在末尾而不将它们标记为坏。 

处理完所有快照后，`bad[i]`直接代表是否是学生`i`曾经被插入到非终止位置。 

关键的不变量是，在任何时刻，链表代表当前已知的所有已验证学生的稳定顺序，指针`cur`始终指示必须与传入快照匹配的下一个所需位置。 任何不匹配只能通过在之前插入新节点来解释`cur`，因为现有节点的相对顺序不能改变。 

这个不变量保证了正确性：我们从不重新排序现有节点，并且仅在因不匹配而强制引入新节点时。 因此，在某个快照中，任何被标记为“差”的学生必定被放置在已经固定的学生之前，这正是切线的定义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("val", "prev", "next")
    def __init__(self, val):
        self.val = val
        self.prev = None
        self.next = None

def append(head_tail, node):
    head, tail = head_tail
    if head is None:
        return (node, node)
    tail.next = node
    node.prev = tail
    return (head, node)

def insert_before(head_tail, cur, node):
    head, tail = head_tail
    if cur is None:
        return append(head_tail, node)
    prev = cur.prev
    node.next = cur
    node.prev = prev
    cur.prev = node
    if prev:
        prev.next = node
        return (head, tail)
    else:
        return (node, tail)

def solve():
    N, M = map(int, input().split())
    bad = [0] * (M + 1)
    pos = [None] * (M + 1)

    head = None
    tail = None

    first = True

    for _ in range(N):
        k = int(input())
        arr = list(map(int, input().split()))

        if first:
            first = False
            for x in arr:
                node = Node(x)
                pos[x] = node
                head, tail = append((head, tail), node)
            continue

        cur = head
        i = 0
        while i < k:
            x = arr[i]

            if cur is not None and cur.val == x:
                cur = cur.next
                i += 1
            else:
                if pos[x] is None:
                    node = Node(x)
                    pos[x] = node
                else:
                    node = pos[x]

                if bad[x] == 0:
                    bad[x] = 1

                head, tail = insert_before((head, tail), cur, node)
                i += 1

    print(" ".join(map(str, bad[1:])))

if __name__ == "__main__":
    solve()
```该解决方案构建了队列的可变链接表示。 这`pos`数组确保每个学生对应一个节点对象，因此我们永远不会重复节点。 这`cur`指针强制与每个快照保持一致：如果匹配，我们前进； 否则我们在该确切位置插入一个新节点。 第一个快照被视为初始化，因为没有与先前的结构相矛盾。 

关键的实现细节是，由于双向链接结构，插入发生在 O(1) 时间内。 这里使用Python列表会导致重复移位并且不会通过约束。

 ## 边缘情况

 第一个重要的边缘情况是仅存在一个快照时。 在这种情况下，没有比较基线，因此即使排序看起来像“剪切”，也无法得到证明。 该算法通过初始化结构来处理这个问题，而不会在第一个快照构建期间将任何学生标记为坏学生。 

另一个边缘情况是所有新学生仅出现在快照的最后。 例如，`[1,2]`其次是`[1,2,3,4]`。 指针`cur`在处理新元素之前到达末尾，因此它们全部被附加并且永远不会被标记为坏，正确地产生全零。 

更微妙的情况是同一位置重复出现不匹配。 假设快照在稳定的骨干元素之前引入了多个新学生。 每个不匹配都会触发之前的插入`cur`， 但`cur`保持固定，直到它与现有节点匹配。 这确保了所有此类学生都被正确标记为已剪切，因为他们都出现在同一快照中已建立的订单位置之前。
