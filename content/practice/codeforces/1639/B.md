 ## 解决方案
 ## 问题理解

 该任务是一个交互式图探索问题。 我们从连通无向图的已知顶点开始。 每个顶点都包含一个宝藏，当我们第一次访问一个顶点时，我们会自动用标志来标记它。 从当前位置我们只能看到每个相邻顶点的度数以及它是否已经包含标志。 我们不知道邻居的实际标签。 

更复杂的是，每次我们输入一个顶点时，邻居的顺序都是独立随机的。 即使我们返回到同一个地方，列表中的第一个邻居也可能对应于与以前不同的边。 图本身永远不会改变，但传出边的编号没有稳定的。 

目标不是重建图表。 我们只需要在使用相当少量的移动的情况下至少访问每个顶点一次。 

该图最多包含 300 个顶点，每个度数最多为 50。如此小的限制意味着任何具有数万步的策略都是可以接受的。 由于比赛材料预先包含完整的图表，参赛者可以根据每次测试调整策略。 然而，预期的想法要简单得多：设计一个更喜欢未探索领域的随机游走。 

最危险的陷阱是假设一条边可以通过它在邻居列表中的位置来记住。 

考虑一条路径```
1 - 2 - 3
```假设我们位于顶点 2 并且交互器当前报告```
degree 1, unflagged
degree 1, flagged
```稍后，返回到顶点 2 后，顺序可能会变为```
degree 1, flagged
degree 1, unflagged
```两次选择“邻居号 1”并不对应于遍历同一条边。 

另一个错误是尝试仅通过度数模式重建顶点。 两个不同的邻居可能具有相同的度数和相同的标志状态。 

例如```
    2
    |
1 - 3 - 4
```顶点 1 和 4 的度数均为 1。当顶点 1 和 4 的度数为 3 时，它们无法区分。 任何分配身份的确定性尝试很容易变得不一致。 

正确的方法是避免完全识别邻居。 

## 方法

 最直接的策略是完全均匀的随机游走。 每当我们到达一个顶点时，我们都会随机均匀地选择它的邻居之一。 

该方法是正确的，因为连通图最终会被概率为 1 的随机游走覆盖。不幸的是，某些图的预期覆盖时间很大。 例如，棒棒糖图是著名的例子，其中纯随机游走需要大约$O(n^3)$在期待中移动。 即使只有 300 个顶点，这也会变得不必要的昂贵。 

关键的观察是交互器告诉我们哪些相邻顶点已经被访问过。 由于我们的目标是发现新的顶点，因此只要存在未标记的邻居，我们就应该始终移动到这样的邻居。 

假设当前顶点有多个邻居，并且至少其中一个尚未被访问过。 转到已标记的邻居并不能立即增加发现的顶点数量，而转到未标记的邻居肯定会增加。 因此，优先考虑未访问过的邻居总是有益的。 

最终我们到达每个相邻顶点都已被看到的区域。 这时我们就需要某种机制来逃脱并继续探索。 在所有邻居中随机选择效果很好。 这会创建一个有偏差的随机游走，只要有可能，它就会积极扩展，否则会徘徊，直到再次到达边界顶点。 

该策略不需要重建图或记住边标识。 它仅使用当前步骤中可用的信息。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力随机游走 | 预期 O(n³) 次移动 | O(1) | O(1) | 已被接受但效率低下|
 | 更喜欢无人拜访的邻居 | 预计实际要小得多，大约为 O(m) 到 O(n²) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从给定的顶点开始。 它立即被视为已访问。 
2. 每当交互器报告当前顶点时，检查所有相邻的描述。 
3. 收集标志等于0的邻居对应的索引。这些代表从未被访问过的顶点。 
4. 如果该集合非空，则选择这些索引之一。 访问这样的顶点会使发现的顶点数量增加 1。 
5. 如果每个邻居都有一个标志，则从所有可用选项中随机选择一个邻居。 这使得步行可以离开死胡同，最终再次到达未探索的区域。 
6. 继续直到交互器输出`"AC"`。 

### 为什么它有效

 该图已连接。 每当存在未访问的邻居时，算法立即发现一个新顶点。 一旦局部邻域耗尽，该过程就变成在已发现的顶点上随机游走。 

连通图上的随机游走以概率 1 到达每个顶点。因此，它最终到达与未发现的顶点相邻的顶点。 在那一刻，算法立即扩展到该顶点。 重复这个论证表明每个顶点最终都会被访问。 

## Python 解决方案

 由于这是一个交互问题，因此代码在每次移动后都会与交互器进行通信。```python
import sys
import random

input = sys.stdin.readline

rng = random.Random()

t = int(input())

for _ in range(t):
    n, m, start, base_move_count = map(int, input().split())

    for _ in range(m):
        input()

    while True:
        parts = input().split()

        if parts[0] == "AC" or parts[0] == "F":
            break

        d = int(parts[1])

        unvisited = []
        all_neighbors = []

        ptr = 2
        for i in range(d):
            deg = int(parts[ptr])
            flag = int(parts[ptr + 1])
            ptr += 2

            all_neighbors.append(i + 1)
            if flag == 0:
                unvisited.append(i + 1)

        if unvisited:
            move = rng.choice(unvisited)
        else:
            move = rng.choice(all_neighbors)

        print(move)
        sys.stdout.flush()
```图描述是在交互开始之前给出的，但本策略不需要它。 这些行将被简单地读取并丢弃。 

对于每个报告的顶点，代码都会扫描邻居描述。 变量`unvisited`存储标志为零的索引。 如果该列表非空，则统一随机选择其元素之一。 否则，将在所有邻居中随机选择一个邻居。 

邻居索引是从 1 开始的，因为交互器期望值从 1 到`d`。 忘记这种转换是导致错误答案的常见原因。 

另一个微妙的细节是每次移动后刷新输出。 如果不刷新，交互器永远不会收到答案，并且解决方案会挂起。

 ## 边缘情况

 考虑有两个顶点的路径。```
1 - 2
```从顶点 1 开始，唯一的邻居未被访问，因此算法立即移动到顶点 2 并结束。 一阶顶点不会造成特殊困难。 

另一个有趣的例子是循环```
1 - 2 - 3 - 4 - 1
```假设我们已经访问过顶点 1、2 和 3。在顶点 2，两个邻居都被标记，因此算法执行随机移动。 最终它到达顶点 3，该顶点仍然有一个未访问的邻居 4。到达这样的边界顶点时，算法再次扩展。 

最后，考虑具有相同度数的对称顶点。 例如，```
    2
    |
1 - 3 - 4
```顶点 1 和 4 的度数均为 1。 该算法从不尝试区分它们。 它只使用它们的标志状态，因此邻居顺序的改变不会使任何存储的信息无效。 这避免了问题的主要困难。
