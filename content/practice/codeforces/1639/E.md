 ## 解决方案
 ## 问题理解

 我们被放置在一个未知的连通无向图中。 我们从一个已知的顶点开始，但之后我们再也不会以有用的方式看到顶点 ID。 每次我们到达一个顶点时，交互器只向我们显示它的度数和随机顺序的邻居列表。 对于每个邻居，我们都会被告知邻居的程度以及我们是否已经访问过该邻居。 

我们可以采取的唯一操作是选择显示的相邻位置之一并移动到那里。 目标是使用尽可能少的移动来访问每个顶点至少一次，并具有软约束，即移动总数应保持在给定基线的一个因子内。 

关键的困难在于邻接表每次访问都会重新洗牌，因此我们不能依靠位置一致性来识别边缘。 唯一持久的信息是邻居是否已被访问，它充当全局进度的本地标记。 

就顶点而言，约束很小，最多 300 个，度数以 50 为界，因此即使是相对简单的探索策略也是可行的。 然而，每次测试最多 60000 步的交互限制意味着我们仍然需要避免病态徘徊，即反复循环而没有取得进展。 

尝试显式重建图结构的简单方法将会失败，因为我们从未观察到邻居的稳定身份。 甚至存储边也是不可能的，因为我们无法一致地标记顶点。 唯一可用的状态是节点是否被访问。 

如果我们尝试“始终访问第一个未访问的邻居索引”，则会出现微妙的失败情况。 由于每次访问的邻居排序都是随机的，这会引入偏差，但不能保证系统性探索，并且在再次找到边界之前，我们可能会陷入在访问区域内反复振荡的困境。 

## 方法

 蛮力的想法会尝试将其视为具有重建的完整图探索问题。 在静态设置中，我们将为邻居分配 ID、存储边并执行标准的 DFS 或 BFS。 这将给出边数的线性遍历复杂性，这是最佳的。 

在这里，这种方法从根本上失败了，因为顶点身份在交互中不是持久的。 每次我们到达一个顶点时，它的邻接列表都会被排列，因此我们无法匹配“这个邻居与之前看到的邻居相同”。 任何重建图表的尝试都会失败。 

关键的观察是我们实际上并不需要重建的图。 我们只需要确保每个顶点最终至少到达一次。 区分进度的唯一信号是为每个邻居提供的已访问标志。 

这将任务变成了具有强偏好规则的引导随机探索。 每当我们位于仍有未访问过的邻居的顶点时，我们应该始终移动到这些邻居之一。 这保证了前进，因为每次这样的移动都会增加访问顶点的数量。 

当不存在未访问的邻居时，当前顶点完全被已访问的节点包围。 在这种情况下，我们就在探索的区域内，我们可以安全地移动到任何邻居。 虽然这可能会导致徘徊，但它最终会回到边界，因为图是连通的，并且边界总是可以通过访问的节点到达。 

该过程的行为类似于没有持久堆栈的 DFS，其中访问集隐式定义了已探索区域和未探索区域之间的边界。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力图重建 | 由于身份丢失而不可能 | O(n + m)（不可用）| 不适用 |
 | 使用访问过的标志进行引导探索 | O(移动 ≤ 60000) | O(n) 隐式 | 已接受 |

## 算法演练

 1. 维护所访问顶点的全局概念，从交互中提供的标志推断出来。 最初仅访问起始顶点。 
2. 在每一步中，读取当前顶点描述，其中以随机顺序列出所有邻居以及每个邻居是否已被访问过。 
3. 扫描邻居列表并收集标记为未访问的邻居的索引。 如果至少存在一个，则选择其中一个，通常是第一个此类索引。 
4. 如果不存在未访问的邻居，则选择任意邻居索引。 为了逃离完全探索的区域并返回仍包含未探索的顶点的区域，此步骤是必要的。 
5. 输出所选索引、刷新并移至下一个交互响应。 

该策略有效的原因是，每次我们选择一个未访问过的邻居时，我们都会严格增加访问过的顶点数量。 由于只有 n 个顶点，因此这种情况最多会发生 n − 1 次。 在这些发现之间，算法可能会漂移，但漂移仅发生在已访问过的组件内。 因为图是相连的，所以这些组件总是有通向未探索领域的边，因此重复遍历最终会再次遇到边界。 

隐式不变量是，所有未访问的顶点仍然可以从当前位置通过某些边序列到达，并且该算法永远不会永久地消除自身到达该边界的能力，因为它永远不会删除边或阻止移动，而只会选择路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, start, base_move_count = map(int, input().split())

        # We do not need to store the graph.
        # The process is fully interactive; we only react locally.

        print(start, flush=True)

        for _ in range(2 * base_move_count):
            line = input().strip()

            # End of current map
            if line == "AC" or line == "F":
                break

            parts = list(map(int, line.split()))
            d = parts[1]

            best = -1

            # neighbors are encoded as (deg_i, flag_i) pairs starting from index 2
            for i in range(d):
                deg_i = parts[2 + 2 * i]
                flag_i = parts[2 + 2 * i + 1]

                if flag_i == 0:
                    best = i + 1
                    break

            if best == -1:
                best = 1  # fallback: all neighbors visited

            print(best, flush=True)

def main():
    solve()

if __name__ == "__main__":
    main()
```该程序的每个交互步骤完全在本地运行。 它从不尝试映射顶点标识； 它只对当前邻接视图中访问过的标志做出反应。 的循环界限为`2 * base_move_count`尊重问题的保证，超过此限制会导致失败，因此我们相应地终止每个地图的探索尝试。 

当访问所有邻居时，一个微妙的细节是后备选择。 选择第一个邻居是任意的，但足够了，因为任何邻居都将行走保持在连接的访问​​区域内，并且最终的边界重新进入仅取决于重复遍历，而不取决于方向选择。 

## 工作示例

 考虑一个小链图，其中 1 连接到 2，2 连接到 3，从 1 开始。 

在顶点 1 处，仅显示邻居 2 并且未被访问，因此我们移动到 2。在顶点 2 处，我们看到一个已访问的邻居 (1) 和一个未访问的邻居 (3)，因此我们移动到 3。在顶点 3 处，所有邻居都被访问，因此我们返回到任何邻居，最终返回到 2，然后在需要时返回 1。 这表明探索在可能的情况下会向外扩展，只有在必要时才会回溯。 

在三角形图 1-2-3-1 中，从 1 开始，我们首先到达 2，然后到达 3。在 3 处，两个邻居都被访问，因此我们可以任意移回到 1 或 2。 即使我们可能会重新访问节点，唯一重要的转换是第一次访问，并且这些转换最多发生在 n − 1 个前向步骤中。 

这些痕迹表明该算法不依赖于结构化回溯。 它仅依靠未访问过的邻居的存在来驱动扩张。

 ## 边缘情况

 一种边缘情况是当算法进入所有相邻顶点都已被访问过的区域时。 例如，在完全探索的三角形中，每个顶点只能看到访问过的邻居。 然后，该算法重复选择任意邻居并在访问集中移动。 尽管这会导致重新访问，但它不会阻止最终完成，因为该组件中的边界已经耗尽，并且剩余的未探索节点必须位于其他地方，可以通过某些访问节点序列到达。 

另一种情况是只能通过一条长期访问的走廊才能进入边境。 在重新遇到走廊入口之前，算法可能会在密集访问的集群内徘徊。 然而，由于每次移动都是允许的并且不会丢失任何状态，因此重复遍历最终会再次跨越该边界，并且当未访问的邻居出现在顶点的本地视图中时，进度会恢复。
