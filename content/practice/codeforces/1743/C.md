 ## 解决方案
 ## 问题理解

 我们有一排盒子。 盒子`i`包含`a[i]`杂志。 二进制字符串告诉我们哪些盒子最初有盖子。 

每个盖子都附在一个盒子上，盒子最初包含`'1'`。 该盖子只有两种选择：留在原处，或者向左移动一个位置。 盖子不能移动多次。 

做出所有决定后，每个盖上盖子的盒子都会将其杂志数量贡献给答案。 目标是最大限度地增加保存杂志的总数。 

有趣的是，盖子是独立的对象，但它们的选择是相互作用的。 盖子位置`i`可以保护任一盒子`i`或盒子`i-1`。 选择一个选项可能会阻止另一个盖子保护更有价值的盒子。 

所有测试用例的总长度最多为`2 · 10^5`，这立即排除了任何二次方。 一个`O(n²)`算法将大致执行`4 · 10^10`最坏情况下的操作，远远超出极限。 每个测试用例我们需要一个线性或近线性的解决方案。 

一些边缘情况会导致贪婪实现失败。 

考虑：```
n = 2
s = 01
a = [10, 1]
```唯一的盖子从位置 2 开始。将其保留在那里可以节省`1`，同时向左移动可以保存`10`。 正确答案是`10`。 始终保护现有有盖盒子的策略将会回归`1`。 

考虑：```
n = 3
s = 011
a = [5, 100, 1]
```最优结果是`105`。 

将盖子从位置 2 移至位置 1，将盖子保持在位置 3。保存的盒子为`{1, 3}`有价值`5 + 1 = 6`，这不是最佳的。 

相反，将盖子保持在位置 2 并将盖子从位置 3 移动到位置 2。由于两个盖子不能占据同一个最终盒子，因此我们需要更好地解释该过程。 正确的贪婪解决方案有效地选择连续块中最好的杂志。 过于简单的本地决策很容易失去价值`100`。 

另一个微妙的情况是：```
n = 4
s = 0111
a = [5, 4, 5, 1]
```答案是`14`， 不是`10`。 

始终保护当前覆盖的盒子的幼稚策略将节省`4 + 5 + 1 = 10`。 将盖子从位置 2 移至位置 1 可以让我们保存`5 + 5 + 4 = 14`。 

关键的观察是，有时我们故意牺牲一个较小的有盖盒子来为较大的无盖盒子腾出盖子。 

## 方法

 强力解决方案将检查每个盖子并尝试两种可能性：留下或向左移动。 如果有`k`盖子，这会创建`2^k`可能的配置。 在最坏的情况下，每个位置都包含一个盖子，所以`k = n`。 

为了`n = 2 · 10^5`， 甚至`2^50`已经不可能了，并且`2^200000`是一个天文数字。 暴力方法是正确的，因为它明确地检查了每项法律安排，但它几乎立即变得无法使用。 

为了找到更快的解决方案，我们需要了解盖子实际上代表什么。 

假设我们遇到一个`'1'`。 这个盖子保证了一小部分局部区域中的一个盒子最终会受到保护。 如果一个`'1'`遵循一个`'0'`，我们有一个选择：要么保护当前的盒子，要么将保护转移到之前未覆盖的盒子上。 

这会在每个连续的段内产生连锁效应。 每当我们看到一个`'1'`又一个`'1'`，可以有效地在该段中的盒子之间重新布置保护。 我们唯一可能丢失的杂志是重新排列区域内的最小值。 

一个特别优雅的贪心过程出现了。 

我们从左到右扫描。 

当我们到达一个包含`'1'`，我们通过添加暂时保存其杂志`a[i]`到答案。 

如果之前的位置是`'0'`，我们发现了一个新块的开始。 我们可能希望将保护向左移动并包含之前的框。 

贪心规则是：

 在活动块内当前选择的受保护盒子中保持最小杂志数量。 

当一个新的`'1'`扩展区块，如果前一个未覆盖的盒子比迄今为止最小的受保护盒子有更多杂志，则用前一个盒子的值替换该最小值。 

这种替换正是最佳重排所要做的。 我们放弃最弱的受保护盒子并保护更有价值的未覆盖盒子。 

结果是线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^k) | O(2^k) | O(k) | 太慢了|
 | 最优贪心 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 将答案初始化为零。 
2. 从左到右扫描阵列。 
3. 什么时候`s[i] = '1'`， 添加`a[i]`因为这个框最初是受保护的，并且是继续受保护的候选者。 
4.如果`s[i] = '1'`和`s[i-1] = '0'`，一个新的块开始。 设置变量`cur`到`a[i]`。 

这里`cur`存储当前在该活动块内选择的最小杂志数量。 
5.如果`s[i] = '1'`和`s[i-1] = '1'`， 更新`cur = min(cur, a[i])`。 

块中的最小受保护值可能已更改。 
6. 每当一个块在零之后开始时，比较未覆盖的框值`a[i-1]`和`cur`。 

如果`a[i-1] > cur`，用这个未覆盖的盒子替换最弱的受保护盒子会增加答案`a[i-1] - cur`。 

将这个差异添加到答案中并设置`cur = a[i-1]`。 
7. 继续直到数组末尾。 

大多数接受的解决方案使用的更易于实施的版本略有不同但等效。 

当我们遇到一个`'1'`经过一个`'0'`，我们启动一个块并跟踪前一个零位置框的值。 随着块的增长，每当新的受保护值大于存储值时，我们就会在概念上交换它们并获得额外的杂志。 

### 为什么它有效

 考虑一个最大线段，如下所示：```
0 1 1 1 1 ...
```该段内的每个盖子只能向左移动一个位置。 最终可以受到保护的盒子总数等于该部分中盖子的数量。 

在由前导零位置和段中的框组成的所有框中，必须将恰好一个框排除在保护之外。 为了最大限度地节省杂志，我们应该排除杂志数量最少的盒子。 

贪婪扫描恰好保持了这个不变性。 随着段的增长，它不断跟踪当前受保护的最小值。 每当出现更好的候选值时，它就会替换那个最小值。 到该段结束时，除了最小值之外的每个值都对答案有贡献，这是最佳选择。 

由于分段是独立的，因此独立优化每个分段会产生全局最优答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        s = input().strip()
        a = list(map(int, input().split()))

        ans = 0
        prev = 0

        for i in range(n):
            if s[i] == '1':
                if i > 0 and s[i - 1] == '0':
                    prev = a[i - 1]

                if prev and prev > a[i]:
                    ans += prev
                    prev = a[i]
                else:
                    ans += a[i]

        print(ans)

solve()
```变量`ans`存储迄今为止保存的杂志总数。 

变量`prev`表示紧邻当前块之前的候选未覆盖框。 当块从位置开始时`i`，框在`i-1`是唯一一个未覆盖的盒子，可以通过盖子移动进入受保护的区域。 

当我们处理一个`'1'`，我们将其值与`prev`。 

如果`prev > a[i]`，保护前一个盒子比保护当前盒子更好。 我们添加`prev`并将较小的值保留为新的候选值，稍后可能会被丢弃。 

如果`prev <= a[i]`，当前的盒子至少同样有价值，因此我们对其进行保护并添加`a[i]`。 

更新内容`prev = a[i]`更换后是微妙的部分。 这意味着较小的值成为当前段中最弱的选择框，稍后可能会被更大的候选框再次替换。 

所有算术都很容易适合 Python 整数，因为最大答案是`2 · 10^5 × 10^4 = 2 · 10^9`。

 ## 边缘情况

 考虑：```
n = 2
s = 01
a = [10, 1]
```在块的开始处，`prev = 10`。 自从`10 > 1`，算法添加`10`和商店`1`作为最弱的值。 最终的答案是`10`，这是最佳的，因为盖子应该向左移动。 

考虑：```
n = 4
s = 0111
a = [5, 4, 5, 1]
```该算法开始于`prev = 5`。 按价值计算`4`，它取代并获得`5`。 按价值计算`5`，它获得`5`。 按价值计算`1`，它获得`4`。 已保存杂志总数相等`14`。 这正是段中最小值的最优排列，即`1`，被排除。 

考虑：```
n = 4
s = 0000
a = [100, 100, 100, 100]
```没有位置包含盖子，因此扫描不会添加任何内容。 答案依然存在`0`，这是正确的。 

考虑：```
n = 4
s = 1111
a = [3, 7, 2, 8]
```前面没有零可以进入保护集。 每个盖子只是保护段内的一些盒子，并且所有四个盒子都可以受到保护。 该算法将所有值相加并返回`20`。
