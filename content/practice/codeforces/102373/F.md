 ## 解决方案
 ## 问题理解

 我们有一个数组`a[1..n]`， 在哪里`a[i]`是该位置的孩子数量`i`。 旧的 Pennywise 采用前缀、位置`1`通过`l`，而现代的 Pennywise 采用后缀，位置`r`通过`n`。 两个段不能重叠，因此`l < r`。 

对于选定的一对`(l, r)`，这两个分数分别是`S1 = a[1] + ... + a[l]`和`S2 = a[r] + ... + a[n]`。 

任务是找到任何有效的对来最小化`|S1 - S2|`，并打印该最小差异以及相应的`l`和`r`。 

约束条件`n <= 10^6`是主要的算法信号。 大约有 100 万个位置，因此`O(n^2)`搜索是完全不可能的。 甚至一个`O(n log n)`这种方法在这里是不必要的，因为正数组值给了我们一个允许线性扫描的单调结构。 值本身可以大到`10^9`，所以总和可以达到`10^15`。 C++ 需要 64 位整数类型来存储这些和，而 Python 整数已经可以安全地处理它们。 

在几种边界情况下，实现可能会悄无声息地失败。 和`n = 2`，唯一合法的对是`l = 1, r = 2`。 用于输入```
2
8 3
```正确的结果是```
5 1 2
```因为这两个分数是`8`和`3`。 在评估初始对之前移动一个指针的实现可能会错过唯一有效的答案。 

当两个初始段已经具有相等的总和时，会出现第二种边缘情况。 为了```
4
7 1 1 7
```这对`l = 1, r = 4`给出分数`7`和`7`，所以答案是```
0 1 4
```在检查差异之前总是执行指针移动的粗心实现可能会错过零的最佳值。 

相反的指针边界也很重要。 考虑```
3
1 2 3
```从第一个和最后一个元素开始给出分数`1`和`3`。 左边的分数较小，所以左边的指针移动到位置`2`, 给予`3`和`3`。 正确的结果是```
0 2 3
```如果条件写得不正确，导致相等或最终有效位置导致额外的移动，则该对`(2, 3)`可以跳过。 

## 方法

 直接方法考虑每一对`(l, r)`满意的`l < r`。 对于每一对，我们可以使用预先计算的前缀和来计算前缀和后缀和，因此每个候选者都采用`O(1)`时间。 有`n(n-1)/2`有效对，即`O(n^2)`。 为了`n = 10^6`，这大约是`5 * 10^11`配对，远远超出任何竞争性编程时间限制所能处理的。 

这两个和的结构为我们提供了更好的搜索方式。 假设当前左分数为`S1`当前的正确分数是`S2`。 每个数组元素都是正数。 如果`S1 < S2`，通过移动来扩展前缀`l`向右一位严格增加`S1`，同时保持右后缀不变。 在这种情况下移动正确的边界将使`S2`较小，但我们可以通过将两个边界视为增加较小边和减少较大边之间的竞争来更直接地进行推理。 

方便的两指针过程从尽可能宽的对开始，`l = 1`和`r = n`。 如果前缀和较小，则提前`l`，因为只有这样较小的金额才能赶上。 如果后缀和较小，则减小`r`，因为只有这样，这个数额才能赶上。 在每个状态之后，我们都会检查绝对差异并保留最好的状态。 

为什么这就足够了？ 前缀和单调增长为`l`向右移动，后缀和单调缩小为`r`向右移动。 最佳对必须出现在这两个单调量交叉点处或附近。 两指针进程直接移向该交叉点并评估其周围所需的每个状态。 

蛮力方法之所以有效，是因为它检查每个可能的边界对。 它失败了，因为这样的对的数量是平方数。 一个和只能向上移动而另一个只能向下移动的观察结果让我们在每次比较后丢弃候选对的整个区域，从而将搜索减少到`O(n)`州。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n^2)`|`O(n)`带有前缀和 | 太慢了 |
 | 两个指针|`O(n)`|`O(n)`| 已接受 |

 ## 算法演练

 1.读取数组并初始化`l = 0`和`r = n - 1`。 这些在内部是从零开始的，所以它们代表位置`1`和`n`在所需的输出中。 放`left_sum = a[l]`和`right_sum = a[r]`。 

该起始状态始终有效，因为`n >= 2`， 所以`l < r`。 
2. 用这两个初始总和之间的差值来初始化最佳答案。 立即存储相应的指针是必要的，因为初始对已经可以是最优的。 
3.同时`l < r`， 比较`left_sum`和`right_sum`。 如果`left_sum <= right_sum`， 进步`l`并添加`a[l]`到左边的总和。 否则，减少`r`并添加`a[r]`到正确的总和。 

当左边的总和较小时，增加前缀是使该边变大的唯一移动。 当右和较小时，递减`r`是向后缀添加另一个元素并使该边更大的运动。 
4. 每次指针移动后，将新的绝对差值与迄今为止找到的最佳差值进行比较。 如果较小，则保存当前指针。 

运动后的状态可能是两个和变得相等或交叉的第一个点，因此仅检查初始状态是不够的。 
5. 停止时`l == r`。 此时，两个选定的段将共享一个位置，因此该对不再有效。 将存储的从零开始的索引转换为从一开始的索引并打印差值，`l + 1`， 和`r + 1`。 

### 为什么它有效

 在每个有效状态下，`left_sum`是结尾于的前缀之和`l`， 和`right_sum`是从以下位置开始的后缀之和`r`。 因为所有`a[i]`是积极的、感动的`l`右严格增加左总和，同时移动`r`左严格增加右总和。 

如果左边的总和较小，任何减少差异的有效尝试都必须增加左边的值，直到它赶上右边的值。 该算法正是这样做的。 对称地，如果右和较小，则扩展右段。 因此，指针总是向两个单调和最接近的点移动。 该算法检查沿该路径的每个状态的差异，包括交叉之前的状态和交叉之后的状态。 因此，这些状态中的最小值是所有有效边界对的全局最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    l = 0
    r = n - 1

    left_sum = a[l]
    right_sum = a[r]

    best_diff = abs(left_sum - right_sum)
    best_l = l
    best_r = r

    while l < r:
        if left_sum <= right_sum:
            l += 1
            left_sum += a[l]
        else:
            r -= 1
            right_sum += a[r]

        if l >= r:
            break

        diff = abs(left_sum - right_sum)
        if diff < best_diff:
            best_diff = diff
            best_l = l
            best_r = r

    print(best_diff, best_l + 1, best_r + 1)

if __name__ == "__main__":
    solve()
```数组被存储是因为右指针可以向左移动，所以算法需要随机访问新包含的元素。 初始金额使用`a[0]`和`a[n - 1]`，表示尽可能小的前缀和后缀。 

比较使用`<=`对于左侧。 如果总和相等，从技术上讲，任一指针都可以移动，但选择左指针就足够了，因为当前状态已被记录为最佳可能差值为零。 

移动指针后，代码首先检查`l >= r`。 这可以防止评估前缀和后缀重叠的无效对。 初始对在进入循环之前单独评估，因此唯一合法的对`n = 2`处理正确。 

Python 的任意精度整数可以安全地存储高达`10^15`。 该算法对于每次指针移动仅执行恒定量的工作，并且每个指针最多移动`n`职位。

 ### 示例 1

```初始前缀包含`5`，而后缀包含最后的`1`。 由于左和较大，右指针向左移动，逐渐放大后缀，直到找到最佳差值。 

|`l`|`r`|`left_sum`|`right_sum`|`diff`| 最佳|
 | --- | --- | --- | --- | --- | --- |

 | 1 | 4 | 5 | 2 | 3 |`3 1 4`|

 下一个动作将使`l = r`，因此算法停止。 最好的有效状态是`l = 1, r = 2`, 有差异`1`，匹配样本。

4

|`l`|`r`|`left_sum`|`right_sum`|`diff`| 最佳|

 最好的状态是`(2, 4)`，其中分数是`3`和`4`。 后面的状态更差，所以存储的答案仍然存在`1 2 4`。

 ## 边缘情况

 对于最小尺寸的情况```
2
8 3
```该算法开始于`l = 0`和`r = 1`, 给出总和`8`和`3`和差异`5`。 循环条件为真，但左和较大导致`r`移动自`1`到`0`。 自从`l >= r`，新状态被拒绝，之前存储的状态对仍然存在`(1, 2)`。 输出是`5 1 2`。 这就是为什么在评估移动状态之前必须进行边界检查。 

对于相等的初始金额，```
4
7 1 1 7
```起始状态有`left_sum = 7`和`right_sum = 7`， 所以`best_diff`立即变为零。 循环稍后可能会移动指针，因为实现使用`<=`，但后来的状态都无法改善零差异。 存储的答案仍然存在`0 1 4`。 

对于跨越边界的情况```
3
1 2 3
```初始状态有总和`1`和`3`。 左边较小，所以`l`变成`2`在一个基于索引和`left_sum`变成`3`。 现在总和相等，差值为零。 下一个移动将使边界重叠，因此不进行评估。 结果是`0 2 3`。 

最大尺寸的情况可以用一百万个来表示。 两项初始金额均已`1`，因此算法无需遍历整个数组即可记录差值零。 输出是`0 1 1000000`。 这个案例证实了该实现处理了最大允许的`n`并且存储数组不会改变渐近复杂度。 

最后的实现细节是所有数组值都是正数。 单调两指针参数取决于此属性。 如果允许零或负值，移动边界将不再保证相应的总和沿可预测的方向变化，并且这个特定的证明将不再适用。
