 ## 解决方案
 ## 问题理解

 我们有一个简单的无向图，最多有 300,000 个顶点和 300,000 个边。 菱形由两个使用相同边的不同三角形组成。 如果一条边有多个顶点连接到其两个端点，则每一对公共邻居形成一个菱形。 

假设边是 (u-v)，并且恰好 (c) 个顶点与 (u) 和 (v) 都相邻。 每个公共邻居都会给出一个包含 (u-v) 的三角形，因此选择任何两个公共邻居都会给出一对共享该边的三角形。 因此，该边缘的贡献为

 [
 \binom{c}{2}=\frac{c(c-1)}2.
 ]

 任务是在每个边上求和该值。 

该图可以包含 300,000 条边，因此检查每对顶点的算法已经太大了。 (O(n^2)) 算法在最大情况下大约有 (9\cdot10^{10}) 个顶点对，而 (O(n^3)) 或 (O(n^4)) 方法完全超出范围。 官方限制为 2 秒和 512 MB，因此该解决方案需要近线性或粗略 (m\sqrt m) 的图形处理，而不是详尽的枚举。 

有几种边缘情况很容易被错误处理。 图形可以包含三角形而不包含任何菱形。 例如，```
4 4
1 2
2 3
3 4
4 1
```根本没有三角形，所以答案是`0`。 将每个三角形视为菱形的三角形计数实现将错误地返回`1`。 

四个顶点的完整图是另一个有用的例子：```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```答案是`6`， 不是`1`。 每条边都属于两个三角形，六个边中的每条边都给出一对三角形。 如果不小心实现，每组四个顶点只计算一次，就会错过五个菱形。 

一条边周围也可以有多个三角形。 考虑```
5 7
1 2
1 3
2 3
1 4
2 4
1 5
2 5
```边 (1-2) 属于三个三角形，使用顶点 (3,4,5)。 这些三角形中的任意两个形成菱形，给出 (\binom32=3)。 计算三角形并简单地除以二是行不通的，因为每个三角形都包含多个菱形。 

## 方法

 最直接的暴力解决方案考虑每个四顶点集。 菱形始终使用四个不同的顶点。 在这四个顶点中有六个可能的边。 如果恰好存在五个，则这四个顶点形成一颗菱形。 如果所有六个都存在，则它们形成一个 (K_4)，其中包含六个不同的菱形，每个共享边的选择一个。 

因此，对于每个四元组，我们可以检查其六个可能的边，并将零、一或六添加到答案中。 这是正确的，但是有

 [
 \binom n4=O(n^4)
 ]

 四倍。 在 (n=300000) 时，这大约是 (3.4\cdot10^{20}) 四元组，甚至还没有考虑每个四元组的六次边缘检查。 该方法仅作为概念基线有用。 

关键的观察是停止直接观察四个顶点。 对于每条边 (u-v)，唯一需要的信息是其公共邻居的数量。 我们可以首先枚举每个三角形并记录属于它的三个边，而不是显式构造每对三角形。 

如果一条边已经出现在 (k) 个三角形中，并且找到了包含该边的另一个三角形，则该新三角形与先前找到的三角形正好形成 (k) 个新菱形。 因此，当发现三角形时，对于其三个边中的每一个，我们都将该边的当前三角形计数添加到答案中，然后增加该边的三角形计数。 

剩下的问题是高效的三角形枚举。 检查每个顶点的每对邻居可以在星形或另一个具有高度顶点的图上进行二次。 解决此问题的标准方法是根据顶点度数确定每条边的方向。 一条边从度数较小的端点到度数较大的端点，打破了顶点数的等度关系。 然后我们只通过这些前向边缘搜索三角形。 

这种度数排序将前向楔形探索的总量限制为 (O(m\sqrt m))，即标准的面向度数的三角形计数界限。 同样的想法通常用于稀疏图中的高效三角形和四周期枚举。 

蛮力之所以有效，是因为每个菱形都是四顶点结构，但会失败，因为四顶点集太多。 观察到菱形只是一对共享一条边的三角形，我们可以将问题简化为三角形枚举，并为每条边加上一个小计数器。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(n^4)) | (O(米)) | 太慢了|
 | 最佳 | (O(m\sqrt m)) | (O(n+m)) | 已接受 |

 ## 算法演练

 1. 读取图并计算每个顶点的度数。 在定向边缘之前我们需要度数，因为方向是使后面的三角形搜索保持较小的原因。 
2. 给每个顶点一个排序`(degree, vertex_id)`。 一条边从该顺序中较小的顶点指向较大的顶点。 等度由顶点数决定，因此每条边都接收一个方向。 
3. 仅存储每个顶点的出边。 与目的地一起存储原始边 ID，因为稍后我们需要更新属于该边的三角形计数。 
4. 维护数组`mark`。 在处理顶点 (v) 时，用边 ID (v-w) 标记每个传出邻居 (w)。 这提供了对 (v) 和标记顶点之间的边的恒定时间访问。 
5. 对于每个出边 (v\rightarrow u)，扫描所有出边 (u\rightarrow w)。 如果(w)当前被(v)标记，则(v,u,w)形成一个三角形。 三个边 ID 立即可知：边 (v-u)、边 (u-w) 和标记边 (v-w)。 
6. 当找到一个三角形时，假设它的三个边当前属于(a)、(b)和(c)先前找到的三角形。 新三角形形成 (a+b+c) 个新菱形，因为它可以与共享任何这些边的每个早期三角形配对。 将该值添加到答案中，然后递增所有三个边缘计数器。 
7. 在移动到下一个顶点之前清除属于 (v) 的传出邻居的标记。 清除步骤可防止标记为一个中心的顶点被误认为是另一中心的邻居。 

### 为什么它有效

 在选定的总排序下，每个三角形都有一个唯一的最小顶点。 它的另外两个顶点都比该顶点大，并且这两个较大顶点之间的边从较小的顶点指向较大的顶点。 因此，当处理三角形的最小顶点时，该三角形只会被发现一次。 

对于每条边，其计数器恰好是迄今为止发现的包含该边的三角形的数量。 当找到包含该边的新三角形时，它会与该边上之前计数的每个三角形形成一个新的菱形。 在增加旧计数器之前添加旧计数器，因此只会对每对三角形计数一次。 由于每个菱形恰好是一对共享一条边的三角形，因此累积的答案正是所需的菱形数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    degree = [0] * n
    edges = [None] * m

    for eid in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges[eid] = (u, v)
        degree[u] += 1
        degree[v] += 1

    order = sorted(range(n), key=lambda v: (degree[v], v))
    pos = [0] * n
    for i, v in enumerate(order):
        pos[v] = i

    out = [[] for _ in range(n)]

    for eid, (u, v) in enumerate(edges):
        if pos[u] < pos[v]:
            out[u].append((v, eid))
        else:
            out[v].append((u, eid))

    triangle_count = [0] * m
    mark = [-1] * n
    answer = 0

    for v in range(n):
        ov = out[v]

        for w, eid in ov:
            mark[w] = eid

        for u, eid_vu in ov:
            for w, eid_uw in out[u]:
                eid_vw = mark[w]

                if eid_vw != -1:
                    answer += (
                        triangle_count[eid_vu]
                        + triangle_count[eid_uw]
                        + triangle_count[eid_vw]
                    )

                    triangle_count[eid_vu] += 1
                    triangle_count[eid_uw] += 1
                    triangle_count[eid_vw] += 1

        for w, _ in ov:
            mark[w] = -1

    print(answer)

if __name__ == "__main__":
    solve()
```第一遍构建`degree`并用稳定的ID存储每条边。 ID 是必要的，因为最终的答案取决于有多少个三角形使用每个特定的边，而不仅仅是取决于总共存在多少个三角形。 

这`order`数组实现度方向。`pos[v]`给出该排序中顶点的位置，因此每个无向边都可以通过一次比较来定向。 传出邻接表包含`(neighbor, edge_id)`对，这使得三角形搜索可以识别所有三个边缘计数器，而无需再次进行字典查找。 

这`mark`每个顶点都会重复使用数组。 加工时`v`,`mark[w]`包含每个前向邻居 (w) 的边 ID (v-w)。 因此，当内循环到达顶点时`w`从`u`,`mark[w] != -1`正是 (v-w) 也存在的条件。 

在三个计数器递增之前更新答案。 如果一条边出现在 (k) 个较早的三角形中，则新三角形会与该边创建 (k) 个新对。 首先更新会计算与其自身配对的新三角形，这是无效的。 

Python 整数具有任意精度，因此即使是最大的可能答案也不会溢出。 例如，具有 775 个顶点的完整图已经有 89,491,021,650 个菱形。 

## 工作示例

 对于示例 1，该图是一个四周期图。 每个顶点都有二度，因此顶点 ID 打破了联系。 没有向前搜索找到三角形。 

| 处理后的顶点 | 转发邻居| 发现三角形| 回答 |
 | ---| ---| ---| ---|
 | 1 | 2, 4 | 无 | 0 |
 | 2 | 3, 4 | 无 | 0 |
 | 3 | 4 | 无 | 0 |
 | 4 | 无 | 无 | 0 |

 这里重要的属性是边可以存在而不参与三角形。 该算法绝不会仅仅因为两条边在一个顶点相交而创建菱形。 

对于示例 2，有两个三角形 (1-2-3) 和 (1-3-4)，共享边 (1-3)。 度数顺序为 (2,4,1,3)。 第一个三角形递增边 (1-2)、(2-3) 和 (1-3) 的计数器。 第二个三角形增加 (1-4)、(3-4) 和 (1-3) 的计数器，并且前一个计数器 (1-3) 贡献一个新的菱形。 

| 处理后的顶点| 三角形| 前边计数器 | 添加到答案 | 回答 |
 | ---| ---| ---| ---| ---|
 | 2 | (1,2,3) | (1,2,3) | (0,0,0) | (0,0,0) | 0 | 0 |
 | 4 | (1,3,4) | 边 (1-3) 有 1 | 1 | 1 |
 | 1 | 无 | 不变| 0 | 1 |
 | 3 | 无 | 不变| 0 | 1 |

 该迹线说明了为什么仅计算三角形是不够的。 第一个三角形没有创建菱形，因为没有任何东西可以与之配对。 第二个三角形与第一个三角形恰好形成一对，给出所需的答案。

 | 时间 | (O(m\sqrt m+n\log n)) | 对顶点进行排序需要 (O(n\log n))； 面向度数的三角形枚举需要 (O(m\sqrt m)) |
