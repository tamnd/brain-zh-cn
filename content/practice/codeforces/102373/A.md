 ## 解决方案
 ## 问题理解

 我们有两个小写字符串，`s`和`t`。 我们需要计算非空子串`s`谁的字母可以取自`t`。 字母的顺序并不重要，因为我们只关心是否`t`包含所选子字符串中出现的每个字符的足够副本。 不同职位在`s`定义不同的子字符串，即使它们的内容相同。 官方声明给出`|s|, |t| <= 10^6`，时间限制为 2 秒，内存为 512 MB。 

例如，如果`s = "aaa"`和`t = "aa"`，三个单字符子串有效，两个长度为 2 的子串也有效，给出`5`。 整个字符串无效，因为它需要三个副本`a`尽管`t`只有两个。 

一百万的大小限制排除了任何二次方。 已经有大约`n(n+1)/2`子串，大致是`5 * 10^11`什么时候`n = 10^6`。 我们需要对每个字符进行恒定的工作量来处理字符串，给出`O(|s| + |t|)`解决方案。 由于字母表仅包含 26 个小写字母，因此保持字符频率需要恒定大小的额外存储空间。 

第一个边缘情况是没有有效的非空子字符串。 例如，```
a
b
```有输出```
0
```因为唯一的子串，`"a"`，需要一个未出现在的字母`t`。 将答案初始化为一个或计算每个可能的起始位置的粗心实现将错误地返回`1`。 

第二个边缘情况是重复字符。 例如，```
aaa
aa
```有输出```
5
```因为所有三个长度为一的子字符串和两个长度为二的子字符串都是有效的。 仅基于每个不同字符是否出现在`t`会错误地接受`"aaa"`以及。 

第三种边缘情况是相同文本的不同出现仍然代表不同的子字符串。 在```
aaa
aa
```位置处的子串`1..2`以及位置处的子串`2..3`两者都被计算在内。 我们计算间隔，而不是不同的字符串。 

第四种边缘情况是子串独立于所有其他子串而有效。 信件的副本在`t`并未在全球范围内被消费。 例如，```
aaaa
a
```有输出```
4
```因为四个单字符子串中的每一个都可以独立地从单个字符组装而成`a`在`t`。 

## 方法

 直接的解决方案可以枚举每个子串`s`。 对于固定的左端点，每次将右端点扩展一个字符，维护当前子字符串中每个字符的频率，并检查这些频率是否符合`t`。 如果检查保持恒定时间，则有`n(n+1)/2`扩展，所以最坏情况的运行时间是`Theta(n^2)`。 为了`n = 10^6`，这大约是`5 * 10^11`子字符串扩展，远远超出了 2 秒的限制允许的范围。 仍然需要在每个分机处重新检查所有 26 个字符计数`Theta(26n^2)`，这是相同的渐近失败。 

有用的观察结果是，有效子串在采用子区间时是封闭的。 如果一个子串可以由`t`，删除字符不能使其无效。 这为每个起始位置提供了单调边界。 对于每个位置`i`， 定义`r[i]`作为最大的右端点，使得`s[i..r[i]]`是有效的。 然后每个子串开始于`i`并于或之前结束`r[i]`也是有效的。 

还有另一个重要的单调性属性。 当起始位置从`i`到`i + 1`，最大有效右端点不能向左移动。 去除`s[i]`使当前窗口更容易满足，所以`r[i+1] >= r[i]`。 官方社论正是利用了这一特性，将独立边界搜索转变为一次滑动窗口传递。 

因此我们可以保留一个窗口`[left, right)`以及该窗口的字符数。 我们延长`right`同时窗口仍然有效。 当添加下一个字符会违反可用计数时`t`，我们停下来。 每个子串开始于`left`并在之前结束`right`是有效的，所以有`right - left`其中。 然后我们删除`s[left]`并移动`left`向前。 因为`right`永远不会向后移动，每个角色最多进出窗口一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O( | s | ²) | O(26) | 太慢了 |
 | 最优滑动窗口 | O( | s | + | t | ) | O(26) | 已接受 |

 ## 算法演练

 1. 阅读`s`和`t`，并计算每个小写字母出现的次数`t`。 这些计数是有效子串可以使用的最大频率。 
2.保留频率数组`have`对于当前窗口`s`。 还保留`right = 0`和一个初始化为零的答案。 当前窗口是`[left, right)`， 所以`right`是当前未包含的第一个位置。 
3. 对于每个`left`从`0`到`len(s) - 1`,尝试延长`right`同时添加`s[right]`不会使其频率超过相应的频率`t`。 每次成功的延期都会保留有效性。 
4. 一旦无法添加下一个字符，当前窗口`[left, right)`是从以下位置开始的最长有效子串`left`。 每个结束位置从`left`通过`right - 1`是有效的，所以添加`right - left`到答案。 
5. 在移至下一个起始位置之前，移除`s[left]`从`have`。 这对应于将窗口从`[left, right)`到`[left + 1, right)`。 我们从不移动`right`向后，因为删除最左边的字符不能使剩余的窗口变得不那么有效。 
6. 打印累计答案。 Python 整数就足够了，因为子字符串的最大数量是`n(n+1)/2`，这大约是`5 * 10^11`为了`n = 10^6`。 

### 为什么它有效

 对于每一个`left`，算法保持不变式`[left, right)`是最长的有效窗口，起始于`left`。 每个较短的窗口结束之前`right`也是有效的，因为它不再使用任何字符的副本。 不能包含下一个字符，因为这样做会超出`t`该字符的可用频率，因此不再是从以下位置开始的子字符串`left`是有效的。 

移除后`s[left]`, 上一个`right`仍然是新起始位置的有效边界，因为删除字符不会增加任何频率。 然后算法扩展`right`仅在必要时。 因此，每个有效子字符串在其自己的左端点处只计算一次，并且不计算无效子字符串。 自从`right`仅向前移动，窗口扩展和移除的总数是线性的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    limit = [0] * 26
    for ch in t:
        limit[ord(ch) - 97] += 1

    have = [0] * 26
    n = len(s)
    right = 0
    answer = 0

    for left in range(n):
        while right < n:
            c = ord(s[right]) - 97
            if have[c] == limit[c]:
                break

            have[c] += 1
            right += 1

        answer += right - left

        c = ord(s[left]) - 97
        if left < right:
            have[c] -= 1

    print(answer)

if __name__ == "__main__":
    solve()
```第一部分构建`limit`， 在哪里`limit[c]`正是角色的多少个副本`c`可以在`t`。 我们永远不需要将字符的实际位置存储在`t`，因为它们的顺序没有相关性。`have`存储当前子串内的频率。 条件`have[c] == limit[c]`意味着添加另一个角色副本`c`会使窗口无效。 我们可以立即停止，而不是添加它并随后修复窗口。 

表达式`right - left`是从以下位置开始的有效子字符串的数量`left`。 该窗口使用半开索引，因此`[left, right)`恰好包含`right - left`人物。 它的非空前缀结束于`left`,`left + 1`， 通过`right - 1`，给出了那么多选择。 

计算完这些子串后，位于的字符`left`被删除。 这`if left < right`Guard 处理窗口为空的情况。 在那种情况下`right == left`，因此没有要从维护的窗口中删除的字符。 这也可以处理其中未出现特定字符的字符串`t`。 

不需要二分查找、后缀结构或二维频率表。 字母表只有 26 个字符，右边界的单调性通过一个移动窗口提供了整个解决方案。 线性时间方法与 ITMO 官方社论中描述的核心思想相同。 

## 工作示例

 ### 示例 1

 输入是```
aaa
aa
```频率限制是两个副本`a`。 窗口的演变如下。 

|`left`|`right`延期前 | 扩展后的窗口 | 添加子字符串 |`answer`|
 | --- | --- | --- | --- | --- |
 | 0 | 0 |`aa`| 2 | 2 |
 | 1 | 2 |`aa`| 2 | 4 |
 | 2 | 3 |`a`| 1 | 5 |

 在`left = 0`，窗口可以包含两个`a`字符但不是三个。 删除第一个`a`使从位置 2 开始的两字符窗口有效，因此`right`不需要向后移动。 在最后的位置只剩下一个字符。 答案是`5`。 

### 示例 2

 输入是```
abacaba
abc
```频率限制为一`a`， 一`b`，和一个`c`。 

|`left`|`right`延期前 | 最长有效窗口 | 添加子字符串 |`answer`|
 | --- | --- | --- | --- | --- |
 | 0 | 0 |`ab`| 2 | 2 |
 | 1 | 2 |`bac`| 3 | 5 |
 | 2 | 4 |`ac`| 2 | 7 |
 | 3 | 4 |`ca`| 2 | 9 |
 | 4 | 6 |`ab`| 2 | 11 | 11
 | 5 | 6 |`ba`| 2 | 13 |
 | 6 | 7 |`a`| 1 | 14 | 14

 该表似乎给出了`14`，但是窗口在`left = 0`实际上可以扩展到`aba`仅当两个`a`角色可用，但它们不可用。 该语句的正确枚举包含七个单字符子字符串、六个有效长度为 2 的子字符串和两个有效长度为 3 的子字符串，例如`15`。 缺失的长度为三的窗口是`bac`在`left = 1`，它已经算作三个子字符串：`b`,`ba`， 和`bac`。 仔细重新计算加法给出`2 + 3 + 2 + 2 + 3 + 2 + 1 = 15`。 因此最终的输出是`15`。 

此示例演示了为什么该算法计算最长有效窗口的所有前缀，而不是仅计算最长子串本身。

 ## 边缘情况

 当没有字符时`s`可用于`t`，窗口无法增长。 为了```
a
b
```最初的`right`是`0`，并尝试添加`s[0]`立即看到`have[a] == limit[a] == 0`。 因此`right - left`为零，答案仍然存在`0`。 进阶后`left`，算法结束时不会计算无效子串。 

通过比较频率而不是仅仅检查字符的存在来处理重复的字符。 为了```
aaa
aa
```的极限`a`是`2`。 从位置零开始，该算法添加两个`a`字符并在第三个字符之前停止。 它贡献`2`，对应于`a`和`aa`。 删除第一个后`a`，窗口仍然包含两个`a`字符，所以第二个起始位置也有贡献`2`。 最后一个位置贡献`1`，生产`5`。 

窗口可以准确地达到可用频率而不会无效。 为了```
abcabc
abc
```前三个字符形成一个有效窗口，因为频率恰好是一个`a`， 一`b`，和一个`c`。 下一个`a`无法添加，因为`t`没有第二个`a`。 因此，该算法计算所有三个非空​​前缀`abc`，然后移动左边界，同时尽可能将右边界保持在同一位置。 

最后，最大尺寸情况揭示了实现是否意外地将右指针向后移动或重新扫描窗口。 拥有一百万`a`两个字符串中的字符，每个子字符串都是有效的，所以答案是`1 + 2 + ... + 10^6 = 500000500000`。 右指针正好前进一百万次，左指针正好前进一百万次，并且不会发生二次枚举。
