 ## 解决方案
 ## 问题理解

 我们有一棵树，其顶点有两种颜色，表示为`0`和`1`。 我们可以翻转一个仍然存在的顶点的颜色，支付一项操作，或者选择一个顶点并销毁包含该顶点的当前颜色的整个连通分量，也支付一项操作。 目标是用尽可能少的操作删除每个顶点。 

答案不仅仅是当前单色分量的数量，因为对精心选择的顶点重新着色可以合并多个分量，并通过一个连锁反应将它们全部删除。 该示例准确地说明了这一点：在具有中心颜色的星形中`1`和三片叶子的颜色`0`，将中心更改为`0`创建一个单色分量，因此两次操作就足够了。 

该树最多包含`200000`顶点。 由于一棵树恰好有`n - 1`边缘，读取和处理输入已经需要线性时间。 在这种规模下，具有二次行为的算法太慢，并且对颜色的指数搜索是完全不可行的。 预期的解决方案只需处理每个顶点和边恒定的次数，给出`O(n)`时间。 

在一些小情况下，肤浅的解决方案可能会失败。 以一个顶点为例，```
1
0
```答案是`1`，因为单个顶点可以简单地被破坏。 总是添加重新着色操作的公式将错误地返回`2`。 

一棵全平等的树，例如```
3
000
1 2
2 3
```也有答案`1`。 每个顶点都属于同一个单色组件，因此一个连锁反应会删除整棵树。 

相反的极端是交替路径：```
3
010
1 2
2 3
```它的答案是`2`。 重新着色中间顶点给出`000`，之后连锁反应消除了一切。 仅计算初始单色分量的方法会看到三个分量并错过有用的重新着色。 

树的结构也很重要。 在```
4
1000
1 2
1 3
1 4
```答案是`2`， 不是`4`：要么破坏黑色中心，然后将白色叶子作为一个组成部分，要么将中心重新着色为`0`并摧毁由此产生的全白树。 

## 方法

 直接的暴力方法是在每个顶点被破坏之前决定它应该具有的颜色。 有`2^n`可能的目标颜色。 对于每个目标着色，我们可以计算有多少个顶点改变了颜色以及它包含多少个单色连通分量，然后取最小值。 评估一种颜色需要`O(n)`时间，因为我们检查每个顶点和边，所以总复杂度是`Theta(n * 2^n)`。 这对于几十个顶点来说已经是无望了，更何况`200000`。 

有用的观察是我们实际上不必模拟链式反应。 

考虑任何完整的操作序列。 为每个顶点指定其被破坏时的颜色。 最终破坏颜色与其初始颜色不同的每个顶点必须至少重新着色一次。 现在查看接收相同破坏颜色的两个相邻顶点。 如果它们在不同的链式反应中被破坏，我们可以在概念上将这些反应合并为一个单色组件，这只能减少破坏操作的次数。 因此，最优策略可以由树的最终二元着色来表示。 

对于固定的最终着色，所需的重新着色操作次数恰好是其与原始着色的汉明距离。 链式反应的数量是最终着色中单色连接组分的数量。 

由于该图是一棵树，因此该组件计数具有特别简单的形式。 从一个组件开始。 端点具有不同最终颜色的每条边将两个组件分开，而端点具有相同颜色的边则保留在一个组件内。 最后，`number of components = 1 + number of edges whose endpoints have different colors`。 

因此，整个问题变得最小化`1 + sum over vertices [final_color != initial_color] + sum over edges [final_color differs across the edge]`。 

这是一个标准的二状态树DP。 对于每个顶点，我们计算该顶点接收最终颜色时其子树的最小成本`0`或者`1`。 子级的贡献仅取决于子级的最终颜色是否等于其父级的最终颜色，因此每个子级都可以独立处理。 

蛮力之所以有效，是因为每种可能的最终着色都描述了组织破坏过程的有效方式，但它失败了，因为着色的数量呈指数级增长。 目标仅由独立的顶点成本和边成本组成的观察结果使我们能够优化这些成本`2^n`树上有两个状态 DP 的选择。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n * 2^n)`|`O(n)`| 太慢了 |
 | 最优树DP |`O(n)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 以顶点为树根`0`。 根的选择是任意的，因为目标是在无向树上定义的。 
2. 对于每个顶点`v`，维持两个值`dp[v][0]`和`dp[v][1]`。`dp[v][c]`是子树贡献的最小成本`v`如果`v`收到最终颜色`c`，排除全局`+1`对应于第一个连接的组件。 
3. 初始化状态`v`及其重新着色成本。 如果原来的颜色`v`已经是`c`，这个成本是`0`; 否则就是`1`。 
4. 处理每个孩子`u`的`v`。 如果`u`收到相同的颜色`c`作为`v`, 边缘`(v,u)`不会创建额外的单色组件边界，因此子组件贡献`dp[u][c]`。 如果`u`接收相反的颜色，边缘是两个组件之间的边界并贡献`dp[u][1-c] + 1`。 

因此固定父颜色的过渡`c`是`dp[v][c] += min(dp[u][c], dp[u][1-c] + 1)`。 

这`+1`第二个选项中的代表端点具有不同最终颜色的边。 
5. 按后序处理顶点，以便在计算其父级之前知道每个子级的 DP 值。 在 Python 中迭代遍历是更可取的，因为树可以是长度的路径`200000`，这将超出 Python 的默认递归调用深度。 
6. 从根本上来说，选择更便宜的最终颜色。 最后添加`1`对于全局元件计数项，给出`answer = 1 + min(dp[root][0], dp[root][1])`。 

额外的`1`总是存在，因为每棵非空树都至少有一个单色分量。 

### 为什么它有效

 对于任何选定的最终着色，每个颜色发生变化的顶点都会花费一次重新着色操作，并且连接不同最终颜色的每条边都会将单色分量的数量恰好增加 1。 由于一棵树从一个组件开始，因此该着色的总成本恰好是 DP 目标加一。 

相反，任何实际的操作序列都可以通过在每个顶点被破坏时为其分配颜色来转换为这样的最终着色。 序列中重新着色的次数至少是最终颜色与其初始颜色不同的顶点的数量，而破坏操作的数量至少是最终着色的单色分量的数量。 因此DP目标不能大于最优操作序列的成本。 对于每一个DP着色，我们可以先进行其所需的重新着色，然后破坏每个单色分量，这样DP值是可以实现的。 这两个方向建立了最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    graph = [[] for _ in range(n)]

    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        graph[a].append(b)
        graph[b].append(a)

    parent = [-1] * n
    order = [0]
    parent[0] = n

    for v in order:
        for u in graph[v]:
            if u == parent[v]:
                continue
            parent[u] = v
            order.append(u)

    dp0 = [0] * n
    dp1 = [0] * n

    for v in reversed(order):
        original = ord(s[v]) - ord('0')

        dp0[v] = 1 if original != 0 else 0
        dp1[v] = 1 if original != 1 else 0

        for u in graph[v]:
            if parent[u] != v:
                continue

            dp0[v] += min(dp0[u], dp1[u] + 1)
            dp1[v] += min(dp1[u], dp0[u] + 1)

    print(1 + min(dp0[0], dp1[0]))

if __name__ == "__main__":
    solve()
```邻接表以通常的无向形式存储树。 由于正好有`n - 1`边缘，它使用线性存储器。 

第一个遍历构造`parent`和`order`。 因为`order`是通过远离根产生的，将其反转给出有效的自下而上的顺序。 这完全避免了递归，这对于具有以下性质的路径形树很有用`200000`顶点。 

两个 DP 阵列独立存储两种可能的最终颜色。 对于原始颜色为的顶点`0`,`dp0[v]`开始于`0`尽管`dp1[v]`开始于`1`。 原版的情况则相反`1`。 

当孩子`u`附着在父母身上被迫着色`0`，只有两种可能。 保持`u`在`0`成本`dp0[u]`，同时给它上色`1`成本`dp1[u] + 1`因为连接边成为单色分量之间的边界。 同样的推理给出了父颜色的过渡`1`。 

测试`if parent[u] != v`是必要的，因为邻接表包含每条边的两个方向。 它可以防止父级被当作另一个子级来处理。 

所有成本至多是`n`，所以Python整数不存在溢出问题。 使用`sys.stdin.readline`保持输入处理线性且足够快`200000`边缘。 

## 工作示例

 ### 示例 1

 输入是```
4
1000
1 2
1 3
1 4
```树的根位于顶点`1`。 叶子是顶点`2`,`3`， 和`4`, 最初都是`0`。 

| 顶点| 原创|`dp0`孩子之前|`dp1`孩子之前| 最终的`dp0`| 最终的`dp1`|
 | --- | --- | --- | --- | --- | --- |
 | 4 | 0 | 0 | 1 | 0 | 1 |
 | 3 | 0 | 0 | 1 | 0 | 1 |
 | 2 | 0 | 0 | 1 | 0 | 1 |
 | 1 | 1 | 1 | 0 | 1 | 3 |

 为根部涂上颜色`0`，每片叶子也可以涂上颜色`0`, 给予成本`0`对于每个孩子。 根本身需要一次重新着色，因此 DP 成本为`1`。 

为根部涂上颜色`1`，保持每片叶子在`0`创建三个边界边，给出成本`3`。 

最终的答案是`1 + min(1, 3) = 2`。 

对应的策略正是样本的策略：recolor vertex`1`，然后销毁单个全白组件。 

### 构造样本 2

 考虑```
3
010
1 2
2 3
```树是一条路，它的颜色交替。 

| 顶点| 原创|`dp0`|`dp1`|
 | --- | --- | --- | --- |
 | 3 | 0 | 0 | 1 |
 | 2 | 1 | 1 | 1 |
 | 1 | 0 | 1 | 2 |

 在顶点`3`, 保持颜色`0`无需花费任何费用，同时将其更改为`1`成本一。 

在顶点`2`, 选择颜色`0`重新着色花费 1，然后可以使用顶点`3`在颜色`0`没有边缘边界，给出`1`。 选择颜色`1`重新着色需要花费一分钱，而孩子可以留下来`0`以额外的边缘成本，还给出`1`。 

在顶点`1`, 选择颜色`0`允许顶点`2`使用颜色`0`有成本`1`，所以子树成本是`1`。 选择颜色`1`比较贵。 

答案是`1 + min(1, 2) = 2`。 

这对应于将中间顶点从`1`到`0`，之后所有三个顶点形成一个单色分量。

 ## 边缘情况

 单顶点情况由 DP 直接处理。 为了```
1
0
```唯一具有最终颜色的状态`0`有成本`0`，而最终颜色的状态`1`有成本`1`。 决赛`+1`给出`1`，这正是所需的一个破坏操作。 

对于已经是单色的树，```
3
000
1 2
2 3
```每个顶点都可以保留颜色`0`。 两条边都有相同的端点，因此都不构成组件边界。 全局常数前的DP值为`0`，答案是`1`。 仅基于重新着色次数的方法会忽略仍然需要一次破坏操作。 

对于交替路径```
3
010
1 2
2 3
```初始颜色由三个部分组成。 摄影指导选择最终颜色`000`，为顶点支付一次重新着色费用`2`和零边边界成本。 添加强制性的第一个组件给出`2`。 这抓住了一个常见的错误，即认为销毁原始组件总是最佳的。 

为了明星```
4
1000
1 2
1 3
1 4
```摄影指导选择最终颜色`0`对于每个顶点。 只有中心改变颜色，所以重新着色成本为`1`，并且所有三个边都有相同的端点，因此没有额外的组件边界。 答案是`1 + 1 = 2`。 

最后，一条路径`200000`等色顶点强调的是实现而不是数学。 迭代父遍历处理路径时无需递归，并且每个 DP 转换都被处理一次。 结果依然`1`，而总工作量随着顶点数量线性增长。
