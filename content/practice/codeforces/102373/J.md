 ## 解决方案
 ## 问题理解

 我们有相同朋友的两种排列。 当前行是`a`，所需的行是`b`。 一次重组选择任何非空的朋友集，将它们从当前位置删除，反转它们的相对顺序，并将反转的子序列放在最前面。 

这项任务是建设性的。 我们不需要尽可能少的重组。 我们只需要输出最多 15 个转换操作`a`进入`b`。 此处提供的语句对应于发布为 102672L、标题为 Transformations 的 Codeforces Gym 问题。 

极限`n <= 10000`是建设的关键。 自从`2^14 = 16384`，十四个二元决策足以为每个朋友提供一个独特的 14 位代码。 这正是我们需要的规模。 一种构造使用`O(n log n)`工作很容易足够快，而任何二次方也可能是可以接受的`n = 10000`，但真正的挑战不是运行时间。 挑战在于找到一种操作次数限制为 15 的结构。 

有几种边缘情况可能会悄无声息地破坏实现。 如果`n = 1`，不需要任何操作，所以答案一定是零。 如果`a`已经等于`b`，零操作也是有效的，尽管一般构造仍然可以产生有效的非空操作序列。 如果某个位没有分配给它的友元，则不得打印该操作，因为该语句要求每个打印操作都选择一个非空集。 最后，排列包含不同的值，因此输入如`1 1 2`不是有效的测试用例。 包含重复值的测试不应用于证明解决方案行为的合理性。 

例如，与```
1
1
1
```正确的输出很简单```
0
```总是创建至少一位操作的粗心实现可能会使用空的选定集打印无效操作。 

为了```
2
1 2
2 1
```一次操作就够了：选择好友`2`。 选定的子序列是`[2]`，所以结果变成`[2,1]`。 如果输出冗余有效操作，假设至少需要两位的实现仍然是正确的，但它绝不能超过 15 个操作的限制。 

## 方法

 直接的暴力方法会尝试为每个操作选择朋友的子集并模拟结果。 即使对于一项操作也有`2^n - 1`可能的子集。 搜索几个操作的序列大致给出`2^(nk)`的可能性`k`的操作，这是完全不可行的。 蛮力是正确的，因为每个合法重组都由这些子集之一表示，但其搜索空间立即变得巨大。 

更自然的贪婪尝试是重复选择应该成为目标排列的下一部分的组。 这正确地捕获了操作，但它没有给出操作数量的可靠界限。 即使另一个重组序列要短得多，排列也可能需要许多这样的贪婪组。 

有用的观察是停止将所选集合视为任意子集，而是给每个朋友一个二进制代码。 手术`i`准确选择其好友`i`第-个代码位是1。 

假设两个朋友有不同的代码。 考虑它们的位不同的最后一个操作。 在此操作期间，恰好选择了其中一个。 选定的朋友被移动到未选择的朋友前面，因此他们的相对顺序在那一刻就确定了。 以后的每个操作要么选择两者，要么都不选择。 选择两者都会颠倒它们的相对顺序，而选择两者都不保持不变。 因此，在所有操作之后，它们的相对顺序仅取决于它们的两个代码，而不取决于它们的初始相对顺序。 

这是核心技巧。 如果每个朋友收到的代码都是不同的，那么所有代码​​位运算后的最终顺序完全由代码本身决定。 我们可以计算一次该顺序，与输入排列无关`a`。 

我们使用`k = ceil(log2(n))`位。 至少有`n`之间的不同代码`0, 1, ..., 2^k - 1`。 我们模拟`k`从数字顺序开始对这些代码本身进行操作。 这给出了所有操作后代码的通用排序。 然后我们分配第一个`n`按照通用顺序将代码按照所需的确切顺序发送给朋友`b`。 

一旦代码被分配，将相应的操作应用于实际的排列`a`产生`b`。 最初的顺序不再重要，因为每个朋友都有一个唯一的代码。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 最坏情况下的 O(2^(nk)) | O(n) | 太慢了 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算最小的数`k`这样`2^k >= n`。 自从`n <= 10000`，我们有`k <= 14`，这已经低于 15 次操作的允许限制。 为了`n = 1`，这给出了`k = 0`。 
2.创建全部`2^k`二进制代码，最初排序为`0, 1, 2, ..., 2^k - 1`。 我们仅将这些代码用作抽象朋友，其身份是其代码编号。 
3. 对于从最低有效位到最高有效位的每一位，对代码序列执行与我们稍后将对真实朋友执行的相同重组。 所选元素是具有该位设置的代码。 它们当前的顺序被颠倒过来，被放置在前面。 毕竟`k`运算后，得到的代码序列就是由构造导出的通用顺序。 
4. 将代码分配给所需的排列`b`根据这个普遍秩序。 如果通用顺序以代码开始`c1, c2, ..., cn`， 分配`c1`到`b1`,`c2`到`b2`， 等等。 现在每个朋友都有一个独特的代码。 
5. 对于每一位，收集分配的代码包含该位的所有好友号码。 这些朋友组成了一个法律重组。 它们的顺序不需要以任何特定顺序打印，因为操作本身使用它们的当前位置来确定反转的子序列。 
6. 如果没有真正的朋友设置了该位，请跳过一点。 这样的操作将是空的并且是不允许的。 剩余操作次数最多为`k <= 14`。 
7. 以构建通用代码顺序时使用的相同位顺序输出这些操作。 该结构保证生成的线完全正确`b`。 

### 为什么它有效

 考虑任意两个具有不同代码的朋友。 让`t`是其代码之间位不同的最后一个操作。 操作前`t`，它们的相对顺序可以是任意的。 操作期间`t`，恰好选择了一个朋友，并且将所选朋友移动到未选择朋友的前面，因此他们的相对顺序完全由他们的两位决定`t`。 以后的每次操作要么选择两个朋友，要么都不选择朋友。 如果两者均未选择，则它们的顺序保持不变。 如果两者都被选择，则两者会一起反转，因此它们的顺序以确定性方式翻转。 因此，它们的最终相对顺序仅是它们的代码的函数。 

因为所有分配的代码都是不同的，所以每对朋友都有一个确定的最终相对顺序。 模拟的代码序列正是这个顺序。 我们分配它的第一个`n`代码给朋友们`b`顺序，因此每对最终的相对顺序与`b`。 由于两者都是相同朋友的排列，因此完整的最终序列必须是`b`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    if n == 1:
        print(0)
        return

    k = (n - 1).bit_length()
    m = 1 << k

    # Find the final order of all k-bit codes.
    order = list(range(m))

    for bit in range(k):
        selected = []
        unselected = []

        mask = 1 << bit
        for x in order:
            if x & mask:
                selected.append(x)
            else:
                unselected.append(x)

        selected.reverse()
        order = selected + unselected

    # The first n codes in this order will be assigned to b[0], b[1], ...
    code_of = [0] * (n + 1)

    for i in range(n):
        code_of[b[i]] = order[i]

    operations = []

    for bit in range(k):
        mask = 1 << bit
        chosen = []

        for friend in range(1, n + 1):
            if code_of[friend] & mask:
                chosen.append(friend)

        if chosen:
            operations.append(chosen)

    print(len(operations))
    for op in operations:
        print(len(op), *op)

if __name__ == "__main__":
    solve()
```第一部分读取两个排列。 不需要构建逆排列，因为该构造将代码直接分配给出现在中的朋友`b`。 

表达式`(n - 1).bit_length()`给出最小的`k`满意的`2^k >= n`。 例如，`n = 8`给出`k = 3`， 尽管`n = 9`给出`k = 4`。 和`n <= 10000`，最大值为 14。 

的`order`数组包含抽象代码而不是朋友号码。 对于一位，该操作正是问题的操作：收集设置了该位的代码，反转它们当前的顺序，并将它们放在没有该位的代码之前。 对每一位重复此操作会产生这些代码在所有实际操作之后将具有的顺序。 

关键的任务是`code_of[b[i]] = order[i]`。 朋友占据位置`i`在所需的排列中接收最终占据位置的代码`i`在抽象构造中。 这将抽象代码实验与实际目标排列联系起来。 

在产生操作时，代码位决定是否选择好友。 朋友号码可以按任意顺序打印，因此从`1`到`n`就足够了。 所选好友的实际顺序是由他们当前的位置决定的，而不是由他们的号码打印的顺序决定的。 

该代码从不使用递归，也从不依赖于普通 Python 整数之外的大整数。 最多有`16384`抽象代码，最多14次传递，因此结构很小。

## 测试用例

 建设性问题的输出不是唯一的，因此将程序的输出与一个精确的样本输出进行比较是不正确的。 下面的测试工具解析生成的操作，模拟它们，并断言生成的排列正是所请求的排列。

import sys
import io
import contextlib

def solution():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    if n == 1:
        print(0)
        return

    k = (n - 1).bit_length()
    m = 1 << k

    order = list(range(m))

    for bit in range(k):
        selected = []
        unselected = []
        mask = 1 << bit

        for x in order:
            if x & mask:
                selected.append(x)
            else:
                unselected.append(x)

        selected.reverse()
        order = selected + unselected

    code_of = [0] * (n + 1)
    for i in range(n):
        code_of[b[i]] = order[i]

    operations = []

    for bit in range(k):
        mask = 1 << bit
        chosen = []

        for friend in range(1, n + 1):
            if code_of[friend] & mask:
                chosen.append(friend)

        if chosen:
            operations.append(chosen)

    print(len(operations))
    for op in operations:
        print(len(op), *op)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    out = io.StringIO()
    with contextlib.redirect_stdout(out):
        solution()

    sys.stdin = old_stdin
    return out.getvalue()

def validate(inp: str) -> str:
    lines = inp.strip().splitlines()
    n = int(lines[0])
    a = list(map(int, lines[1].split()))
    b = list(map(int, lines[2].split()))

    output = run(inp)
    tokens = list(map(int, output.split()))
    ptr = 0

    k = tokens[ptr]
    ptr += 1

    assert 0 <= k <= 15

    cur = a[:]

    for _ in range(k):
        c = tokens[ptr]
        ptr += 1

        assert 1 <= c <= n

        chosen = tokens[ptr:ptr + c]
        ptr += c

        assert len(chosen) == c
        assert len(set(chosen)) == c
        assert all(1 <= x <= n for x in chosen)

        chosen_set = set(chosen)

        selected = [x for x in cur if x in chosen_set]
        remaining = [x for x in cur if x not in chosen_set]

        cur = selected[::-1] + remaining

    assert ptr == len(tokens)
    assert cur == b

    return output

 ## 边缘情况

 对于`n = 1`,`(n - 1).bit_length()`为零。 该代码显式处理此问题并打印零操作。 这避免了尝试用不必要的操作构造位宇宙，并直接处理唯一不需要二元决策的情况。 

对于已经相等的排列对，一般构造仍然有效，因为它将唯一的代码分配给目标位置并应用相应的操作。 没有必要特殊情况`a == b`，尽管这样做会产生较小的零运算输出。 这很有用，因为建设性问题判断结果状态，而不是答案是否使用最小步数。 

为了`n`略高于 2 的幂时，位数正好增加 1。 例如，`n = 8`需要三位，因为`2^3 = 8`， 尽管`n = 9`需要四个，因为三个位仅提供八个不同的代码。 表达式`(n - 1).bit_length()`处理此边界时不会出现差一错误。 

对于最大情况`n = 10000`，十四位提供`16384`不同的代码。 仅将诱导顺序中的前 10000 个代码分配给真正的朋友。 未使用的代码永远不会出现在任何操作中，因此它们对实际行没有影响。 这就是为什么该构造可以使用大于`n`没有任何特殊的填充逻辑。 

在问题的输入契约下，重复值不是合法的边缘情况。 两个数组都是排列，因此每个朋友号码只出现一次。 构建的实现`code_of`因此，通过朋友号码是安全的，并且不需要碰撞处理。 

最后，不得打印未选择好友的操作。 代码在构建友元代码后过滤掉这些位。 由于总共最多有 14 位，因此删除空操作会使答案安全地低于所需的最大值 15。
