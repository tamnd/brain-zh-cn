 ## 解决方案
 ## 问题理解

 我们拥有一个完整的火车站网络，每个车站都有一位乘客在固定的时间戳出现。 在任意两个站点之间行驶需要花费已知的时间，并且该行驶时间不一定是对称的。 

托马斯从 1 号站出发，但他不会立即自动收集任何东西。 仅当托马斯在乘客出现时恰好在车站时，才会进行接载。 他可以根据需要在车站等候，但一旦离开车站，时间就会按旅行费用提前。 目标是选择一系列要访问的车站，以便每次移动都准确地落在乘客到达时间，从而最大限度地收集乘客数量。 

关键的限制是，只有当到达时间条件完美匹配时，从 i 站移动到 j 站才有用。 如果托马斯到达得太早或太晚，那么这种转换是没有用的，因为到达后等待无助于解决所需接送时间的不匹配问题。 

问题大小为 N 到 500，这排除了立方或更差的站对结合额外因素的结构。 二次结构仍然是可以接受的，这表明我们应该从成对转移和状态动态规划的角度来思考。 

一个微妙的边缘情况来自于时间不符合任何一致链的电台。 例如，一个站点可能在行程时间方面是可达的，但在精确的时间戳匹配方面却不是。 考虑这样的情况：```
3
1
100
2
0 1 1
1 0 1
1 1 0
```尽管就行程而言，一步即可到达每个站点，但只有满足精确时间差的转换才有效，因此大多数边缘变得不可用。 天真的最短路径思维会错误地认为连通性意味着可行性，但这里时间一致性是可达性的唯一有效概念。 

另一个特殊情况是，在第一次取货后，站 1 不再是最佳链的一部分。 由于 Thomas 从站点 1 开始，只有在恰好到达 T1 时才在那里收集，因此我们必须将站点 1 视为唯一的初始激活状态。 任何假设所有站点都可以作为起点的方法都会计算过多。 

## 方法

 暴力策略是将每个可能的站点序列视为候选路径，并模拟托马斯是否可以遍历它。 对于 k 个站点的固定排序，检查可行性需要验证每个连续转换是否满足行程时间和时间戳差之间的相等条件。 这已经花费了 O(k)，并且有 N！ 最坏情况下的排列，即使对于小 N 也是完全不可行的。 

一种更结构化的暴力方法通过从站点 1 开始进行深度优先搜索，尝试所有满足时间约束的下一个站点，从而稍微改进了这一点。 即便如此，每个状态都会分支到最多 N 个可能性，并且由于我们正在有效地探索密集图中的所有简单路径，因此状态的数量呈指数级增长。 

关键的观察是从 i 移动到 j 的可行性仅取决于 i 和 j，而不取决于完整的路径历史。 如果 Thomas 在时间 T_i 到达站 i，则当且仅当 D[i][j] 等于 T_j 减去 T_i 时，恰好在 T_j 到达站 j 才有效。 这消除了任何中间推理的需要。 该结构变成一个有向图，其中仅当该等式成立时才存在边。 

一旦问题被视为一个图，目标就变成在有向非循环结构中找到从站 1 开始的最长路径。 循环不能存在于时间一致的边沿中，因为时间沿着任何有效边沿严格增加。 这允许动态编程解决方案，我们可以计算在每个站点结束的最佳链。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解（所有路径）| O(N!) | O(N) | 太慢了|
 | 有效转换上的 DFS | O(exp N) | O(N) | 太慢了|
 | 时间一致图上的 DP | O(N^2) | O(N^2) | O(N^2) | O(N^2) | 已接受 |

 ## 算法演练

 我们将问题转换为有效的时间一致转换图，然后计算从站 1 开始的最长有效链。 

1. 定义一个状态 dp[i]，表示如果最后一次接载是在 i 站，则可以接载的最大乘客数量。 这是有效的，因为一旦我们修复了最后一个站点，早期的决策就不再重要，除非通过最佳可能的链到达它。 
2. 如果等待时间 T1 可以立即收集站 1，则初始化 dp[1] = 1。 这始终是允许的，因为等待没有限制。 
3. 最初将所有其他 dp 值设置为 0，这意味着除非另有证明，否则它们无法访问。 
4. 对于每对站 (i, j)，检查是否存在从 i 到 j 的有效转换。 这需要验证 T_j 严格大于 T_i 并且 D[i][j] 等于 T_j 减去 T_i。 
5. 如果转换有效，则更新 dp[j] = max(dp[j], dp[i] + 1)。 这反映了以 i 结尾的最著名链的扩展。 
6. 按照 T_i 的递增顺序处理站，以便当我们评估 dp[i] 时，所有早期时间都已被充分考虑。 这保证了我们永远不会错过有效的时间进程。 
7. 处理完所有转换后，答案是所有 dp[i] 的最大值，因为最佳链可以在任何站结束。 

### 为什么它有效

任何有效的拾取顺序都必须满足连续站点之间严格的时间对齐。 该条件强制沿路径严格增加时间序列。 由于这种单调性，每条有效路线都会形成一个按时间排序的站点的有向无环图。 

动态编程状态捕获在每个节点结束的最优链。 由于每个转换都准确地保留了可行性，并且考虑了所有可能的有效前驱，因此 dp[i] 始终存储以 i 结尾的最佳可能链。 不能错过更好的解决方案，因为任何以 i 结束的最佳链都必须以某个有效的前驱 j 结束，并且在处理 j 时将评估该转换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N = int(input())
    T = [0] * N
    for i in range(N):
        T[i] = int(input())
    
    D = [list(map(int, input().split())) for _ in range(N)]
    
    dp = [0] * N
    dp[0] = 1
    
    for i in range(N):
        if dp[i] == 0:
            continue
        for j in range(N):
            if i == j:
                continue
            if T[j] > T[i] and D[i][j] == T[j] - T[i]:
                dp[j] = max(dp[j], dp[i] + 1)
    
    print(max(dp))

if __name__ == "__main__":
    solve()
```其实现直接反映了 DP 的表述。 关键细节是我们只从已经可达的状态进行传播，这可以防止不相关的转换污染 DP 表。 条件`D[i][j] == T[j] - T[i]`强制执行精确的时间匹配，时间戳的严格不等性保证了时间的一致性。 

站点 1 的种子值是 1，因为 Thomas 从那里开始并且可以等到乘客到达。 没有其他站被初始化，因为所有其他拾取器都需要有效的传入转换。

 ## 边缘情况

 当站 1 无法到达具有有效时间差的任何其他站时，就会出现一种边缘情况。 在这种情况下，DP 永远不会扩展到超出 dp[1] = 1，并且答案正确地保持为 1。该算法自然地处理此问题，因为没有转换满足相等条件，因此不会发生更新。 

另一种情况是当一个站具有来自多个前任站的有效传入边沿时。 DP更新规则保留最大链长度，因此即使较短的路径首先到达它，后来的较长路径也会覆盖它。 由于所有转换都是对对的独立检查，因此会考虑每个可能的前驱，确保始终保留最佳链。 

第三种情况涉及具有相同时间戳的站点。 由于 i != j 时行程时间严格为正，因此条件 T[j] > T[i] 会阻止任何在相等时间站点之间移动的尝试，从而防止无效的零持续时间转换。
