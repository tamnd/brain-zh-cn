 ## 解决方案
 ## 问题理解

 游戏的每次运行都会记录一系列分割时间，并且每次运行都包含相同数量的分割。 您可以将输入视为一个矩阵$N$行和$K$列，其中行$i$存储运行中每个分段所花费的时间$i$，并且各列对应于不同运行中的相同游戏目标。 

对于任何查询，我们都会得到一个分割索引$s$。 任务是只查看列$s$，提取$N$该分组的所有运行的值，并计算任意两次运行之间的最大改进。 改进意味着稍后的运行更快或更慢的差异，但由于每次运行中的时间都严格增加，因此有意义的解释只是该列中任何两个值之间的最大差异，即$\max(t_i[s]) - \min(t_i[s])$。 

因此，每个查询的核心输出与运行之间的顺序无关，并且仅取决于单个列中的值的范围。 

约束允许最多$N, K \le 700$，这使得存储值的总数最多为 490,000。 查询数量$Q$可以大到$10^5$，它足够大，如果天真地完成，重新计算每个查询的列范围会太慢。 

一个简单的解决方案，扫描所有$N$每个查询的运行成本$O(NQ)$，这变成了关于$7 \times 10^7$最坏情况下的操作。 这是临界点，但没有必要，因为可以进行预处理。 

一个关键的边缘情况来自重复查询。 如果相同的分割索引出现多次，则重复重新计算其最小值和最大值会浪费时间。 

另一个微妙的点是，每次运行的值在分割之间严格增加，但此属性在单个列中没有帮助； 它只保证行内的结构，而不保证跨行的结构。 

## 方法

 蛮力的想法很简单。 对于每个查询，我们迭代所有运行，收集请求的分割的值，并计算最小值和最大值。 答案是他们的差异。 这是正确的，因为改进定义减少到该列内的最大分布。 

问题是效率。 每次查询的成本$O(N)$， 所以$Q$查询成本$O(NQ)$。 和$N = 700$和$Q = 100000$，这达到了 7000 万次操作，而在 Python 中，这是不必要的开销，尤其是在重复扫描和索引的情况下。 

关键的观察结果是每个查询仅依赖于固定矩阵的单列。 由于矩阵永远不会改变，我们可以预先计算每列的最小值和最大值一次。 之后，通过减去预先计算的值，在恒定时间内回答每个查询。 

我们用重复扫描换取一次性扫描$O(NK)$预处理步骤。 这很容易满足限制，因为最多为 490,000 次操作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(NQ)$|$O(1)$额外 | 太慢了|
 | 预先计算每列的最小值/最大值 |$O(NK + Q)$|$O(K)$| 已接受 |

 ## 算法演练

 我们构建两个大小的数组$K$：一个用于每个拆分的最小值，一个用于每个拆分的最大值。 

1.初始化两个数组`mn`和`mx`大小的$K$。 全部设置`mn`值为一个非常大的数字并且所有`mx`值变为一个非常小的数字。 这使我们能够安全地更新每列的极值。 
2. 逐一阅读每个运行。 对于每次运行，迭代其$K$分割值。 对于职位$j$， 更新`mn[j] = min(mn[j], value)`和`mx[j] = max(mx[j], value)`。 这确保了在处理所有运行之后，每列存储其全局最小值和最大值。 
3.对于每个查询，读取分割索引$s$，将其转换为从零开始的索引，并输出`mx[s] - mn[s]`。 

正确性来自于每个查询都要求固定列中任意两个元素之间的最大差异。 唯一重要的候选者是该列的全局最小值和全局最大值，因为任何其他对都会产生较小的差异。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, K, Q = map(int, input().split())

    INF = 10**18
    mn = [INF] * K
    mx = [-INF] * K

    for _ in range(N):
        row = list(map(int, input().split()))
        for j in range(K):
            v = row[j]
            if v < mn[j]:
                mn[j] = v
            if v > mx[j]:
                mx[j] = v

    for _ in range(Q):
        s = int(input()) - 1
        print(mx[s] - mn[s])

if __name__ == "__main__":
    solve()
```该实现维护两个按分割位置索引的数组。 预处理循环确保在输入矩阵的单次传递中计算每列的极值。 查询处理被简化为直接数组查找和减法。 

这里的一个常见错误是重新计算每个查询的最小值和最大值或错误地重置每行的数组。 另一个微妙的问题是忘记将查询索引从基于 1 的转换为基于 0 的索引，这会默默地将答案转移到错误的拆分。

 ## 边缘情况

 单次运行的最小输入显示每列的改进为零，因为最小值等于最大值。 预处理正确初始化，因为每个值都将两个边界更新为相同的数字，并且查询正确返回零。 

所有运行每列共享相同值的情况测试算法是否意外累积行间差异。 由于每列的最小值和最大值保持相等，因此减法结果为零，符合预期行为。 

值变化很大但未在运行之间排序的情况证实运行的顺序并不重要。 该算法仅依赖于极值，因此行的任何排列都会产生相同的结果，并且计算保持稳定。
