 ## 解决方案
 ## 问题理解

 我们得到了一系列的堆，每堆都包含一定数量的毛绒动物。 在一次移动中，我们可以将任何单堆的大小增加或减少恰好一，并且我们可以根据需要多次执行此操作。 目标是修改桩，以便我们可以选择一组恰好为 L 的桩，并使该组中的所有桩包含相同的最终数量的毛绒动物，同时最小化操作总数。 

更具体地说，我们可以从 P 中挑选 L 堆，并转换它们的值，使它们变得相同，并且每增加或减少一个单位都需要一次操作。 剩下的 P − L 堆并不重要。 

约束 P ≤ 10^5 立即排除尝试所有大小为 L 的子集的解决方案，因为这在组合上是不可能的。 即使天真地检查所有候选目标值也会太慢，除非每次检查都接近线性或对数线性。 这推动我们走向排序和基于前缀的优化或滑动窗口结构。 

一个微妙的陷阱是解释“任何 L 堆将具有相同数量”这句话。 这并不意味着大小为 L 的所有子集必须同时匹配，这只有在所有堆都相等时才可能实现。 相反，这意味着我们选择 L 堆，并以最小的成本使它们相等。 误读这一点会导致不可能或微不足道的解释。 

另一种边缘情况是当 L 非常小或非常接近 P 时。如果 L = 1，则不需要任何操作，因为单个堆已经非常均匀。 如果 L = P，问题就变成使所有桩等于某个值，这减少了选择全局目标并支付绝对偏差的问题。 

## 方法

 一种直接的方法是尝试 L 堆的每个子集，并为每个子集尝试每个可能的最终值。 对于固定子集，最佳最终值是该子集的中值，因为最小化绝对偏差是通过选择中值来解决的。 成本就是到该中位数的距离之和。 

然而，枚举子集是指数级的。 即使我们修复了一个子集，重新计算中值和成本至少是线性的，这会导致不可行的 O(2^P) 或 O(P^2) 式解决方案，具体取决于实现。 

关键的结构观察是，一旦数组排序，L 个元素的任何最佳选择都必须来自连续的块。 如果我们选择不相邻的元素，用更接近的中间值替换它们只会降低成本，因为绝对偏差在线上是凸的。 这意味着我们只需要考虑排序数组中大小为 L 的窗口。 

对于每个窗口，最佳目标值是该窗口的中值元素。 通过前缀和，我们可以计算在常数时间内使窗口中的所有元素等于中位数的成本。 这减少了扫描所有窗口并采取最小成本的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集 | O(选择(P, L) · L) | O(1) | O(1) | 太慢了|
 | 排序+滑动窗口+前缀和| O(P 日志 P) | O(P)| 已接受 |

 ## 算法演练

1. 按非降序对堆大小数组进行排序。 排序使我们能够将最佳组推理为连续的段，因为值的接近性变成了索引的局部性。 
2. 在排序后的值上构建前缀和数组。 这使我们能够在 O(1) 内计算任意区间的总和，这对于快速成本评估是必要的。 
3. 考虑排序数组中长度为 L 的每个连续段。 每个这样的段代表可以均衡的 L 堆的候选选择。 
4. 对于每个段，确定中值元素。 对于从 i 到 i + L − 1 的段，中位数位于位置 i + L // 2。中位数使段内的总绝对偏差最小化。 
5. 计算使线段中所有元素等于中位数的成本。 将线段围绕中位数分为左右部分，然后使用前缀和来计算两侧所需的总调整量。 
6. 跟踪所有细分市场的最低成本。 这个最小值代表了L桩的最优选择和最优目标值。 

### 为什么它有效

 正确性依赖于两个属性。 首先，对于任何固定的数字集，最小化绝对差之和的值是中位数。 其次，在排序数组中的所有 L 个元素的选择中，最优集合必须由连续的元素组成； 否则，更换具有更接近中间值的间隙元件不会增加成本，而且通常会降低成本。 这两个事实将搜索空间从任意子集减少到排序数组上的滑动窗口，从而保证检查全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    P, L = map(int, input().split())
    S = list(map(int, input().split()))
    
    S.sort()
    
    prefix = [0] * (P + 1)
    for i in range(P):
        prefix[i + 1] = prefix[i] + S[i]
    
    def range_sum(l, r):
        return prefix[r + 1] - prefix[l]
    
    INF = 10**30
    ans = INF
    
    for i in range(P - L + 1):
        j = i + L - 1
        m = i + L // 2
        median = S[m]
        
        left_cost = median * (m - i) - range_sum(i, m - 1)
        right_cost = range_sum(m + 1, j) - median * (j - m)
        
        ans = min(ans, left_cost + right_cost)
    
    print(ans)

if __name__ == "__main__":
    solve()
```排序步骤是将问题转化为区间选择的结构转换。 前缀和数组用于在恒定时间内评估每个候选区间。 在循环内部，直接选择中值索引而不是重新计算，从而避免了对额外数据结构的任何需要。 

一个常见的错误是当 L 为偶数时错误处理中间位置。 在这里，选择两个中间位置中的任何一个对于绝对偏差来说都是等效的，并且实现始终选择上中位数。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    P, L = map(int, sys.stdin.readline().split())
    S = list(map(int, sys.stdin.readline().split()))

    prefix = [0]
    for x in S:
        prefix.append(prefix[-1] + x)
    
    def rs(l, r):
        return prefix[r + 1] - prefix[l]
    
    INF = 10**30
    ans = INF

        left = median * (m - i) - rs(i, m - 1)
        right = rs(m + 1, j) - median * (j - m)
        ans = min(ans, left + right)
    
    return str(ans)

 ## 边缘情况

 当所有堆已经包含相同数量的毛绒动物时，每个窗口产生的成本为零，因为中位数等于段中的每个元素。 该算法评估每个窗口，但始终根据前缀和计算零，因此最小值保持为零。 

当L等于1时，每个窗口由单个元素组成，中位数是元素本身。 左右成本表达式的计算结果均为零，因为该段中没有其他元素，并且算法无需特殊大小写即可正确返回零。 

当值包含远离密集簇的极端异常值时，排序步骤会将簇隔离到连续的窗口中。 仅捕获密集区域的窗口会产生较小的中值偏差，而包含异常值的窗口会产生较大的成本。 最小值正确地选择了密集区域窗口，并且前缀和确保了异常值的贡献不会以错误的方式被部分计算。
