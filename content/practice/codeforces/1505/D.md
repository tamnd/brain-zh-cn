 ## 解决方案
 ## 问题理解

 我们被要求确定某个数字是否$N$可以表示为整数的幂之和$M$，每种力量最多使用一次。 同样，我们想知道是否$N$在基地有代表$M$仅使用数字 0 或 1。输入由两个整数组成，$N$和$M$， 在哪里$N$最大为 1024 并且$M$介于 2 和 16 之间。如果存在这种表示，则输出只是“YES”，否则输出为“NO”。 

限制很小：$N$最多 1024。这意味着即使是迭代所有幂的算法$M$最多$N$会跑得很快。$M$最多为16，所以我们需要考虑的最大幂序列是$16^0, 16^1, 16^2, \dots$，呈指数增长，并在远低于 1024 时停止。这些界限意味着任何迭代尝试所有幂或使用重复除法/模运算的算法都是可行的。 

不明显的边缘情况是$N$相同的幂需要多个系数。 例如，如果$N=6$和$M=2$，贪婪地减去最大幂的天真的方法可能会产生类似的结果$4 + 2 = 6$，这是可行的，但是如果我们误解了条件并允许多次计算幂，我们可能会错误地尝试$2 + 2 + 2 = 6$，这是无效的。 另一个微妙的情况是当$N$正好是$M$，它应该始终返回“YES”。 

例如，输入`N=5, M=2`应返回“YES”，因为 5 = 4 + 1。输入`N=8, M=2`应该返回“YES”，因为 8 = 8。如果粗心的算法无法正确处理类似二进制的分解，则可能会在有效情况下返回“NO”。 

## 方法

 蛮力方法将尝试迭代所有权力子集$M$不超过$N$并对它们求和。 对于每个幂，我们可以包含它也可以不包含它，并检查总数是否等于$N$。 由于相关权力的数量最多为$\log_M N$，这种方法在理论上对于这些约束是可行的，但子集枚举是不必要的。 

关键的观察是，问题简化为检查数字是否$N$在基地$M$全部为 0 或 1。如果基数中有任何数字$M$表示大于 1，则必须多次使用某种幂来求和$N$，这是不允许的。 这允许使用重复除法和模运算得到简单而快速的解决方案。 

蛮力之所以有效，是因为所有权力子集的总和为$N$，但如果使用显式子集枚举实现，就会变得很麻烦。 基本转换观察使我们能够将问题简化为检查简单的数字条件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 权力的子集枚举| O(2^log_M(N)) | O(2^log_M(N)) | O(log_MN) | O(log_M N) | 矫枉过正，不必要|
 | Base-M 数字检查 | O(log_MN) | O(log_M N) | O(1) | O(1) | 高效、被接受|

 ## 算法演练

 1. 初始化变量`current`等于`N`。 我们将反复检查每个基地 -$M$数字。 
2. 虽然`current`大于零：

 1. 计算`current % M`，它给出了基 $M` 中的最低有效数字。 
2. 如果该数字大于1，则输出“NO”并终止，因为大于1的数字表示某个数字的幂$M$需要使用多次。 
3. 否则，划分`current`经过`M`（整数除法）并继续。 
3. 如果循环完成后没有找到大于 1 的数字，则输出“YES”。 

为什么它有效：在每次迭代中，我们检查当前功率的系数$M$。 如果所有系数均为 0 或 1，则根据定义$N$可以表示为不同幂的总和$M$。 不变的是`current`总是代表剩余部分$N$分解，任何违反 0-1 系数条件的行为都会立即发出不可能分解的信号。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    N, M = map(int, input().split())
    current = N
    while current > 0:
        digit = current % M
        if digit > 1:
            print("NO")
            return
        current //= M
    print("YES")

if __name__ == "__main__":
    main()
```该解决方案读取输入并将其存储在`current`用于分解。 在每一步，它都会计算最不重要的基数$M$使用模数的数字。 如果数字超过 1，则立即打印“NO”并退出，防止进一步不必要的计算。 否则，它除以$M$移动到下一个更高的功率。 完成后，如果没有发现无效数字，则打印“YES”。 边缘条件如$N=1$或者$N=M$由该循环自动处理。 

## 工作示例

 ### 示例 1

 输入：`2 3`| 当前| 数字 = 当前 % M | 行动|
 | --- | --- | --- |
 | 2 | 2 % 3 = 2 | 数字 > 1，打印“NO” |

 输出：`NO`**解释：** 2 不能表示为 3 的不同幂的和，因为最小的幂是 1 和 3。 

### 示例 2

 输入：`5 2`| 当前| 数字 = 当前 % M | 行动|
 | --- | --- | --- |
 | 5 | 5 % 2 = 1 | 继续，当前 = 5 // 2 = 2 |
 | 2 | 2 % 2 = 0 | continue, current = 2 // 2 = 1 |
 | 1 | 1 % 2 = 1 | continue, current = 1 // 2 = 0 |

 输出：`YES`**解释：** 5 = 2^2 + 2^0 = 4 + 1，有效分解。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |

 ## 边缘情况

 对于`N=1, M=16`,`current`从1开始，数字=1，有效，循环结束，输出“YES”。 

为了`N=1024, M=2`，循环迭代每个二进制数字。 由于1024是2^10，除了一位之外的所有数字都是0，所以输出“YES”。 

为了`N=6, M=2`，分解尝试 6 % 2 = 0，然后 3 % 2 = 1，然后 1 % 2 = 1，剩余 0。由于没有数字超过 1，因此输出“YES”。 等等，检查一下：6 的二进制是 110，数字 1,1,0，有效。 更正：前面的“NO”示例是错误的。 正确的输出应该是“YES”。 

这凸显了仔细追踪的重要性。 该算法通过检查每个基于 M 的数字来正确处理所有边缘情况。
