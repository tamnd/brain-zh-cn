 ## 解决方案
 ## 问题理解

 我们有一个以网格表示的教室。 每个单元格要么是空的（`.`) 或被占用 (`*`）。 

我们想要准确的座位`k`学生们排成一条直线。 座位必须是连续的，并且必须完全位于单行或完全位于单列内。 所选航段中的每个座位都必须是空的。 

任务是计算存在多少个不同的有效段。 

段由其占用的单元集来标识。 例如，如果一行包含四个连续的空座位并且`k = 2`，然后间隔`[1,2]`,`[2,3]`， 和`[3,4]`是三种不同的安排。 

网格尺寸可以大到`2000 × 2000`。 这意味着网格可能包含多达四百万个单元。 任何重复扫描相同单元或独立检查每个可能片段的解决方案都会变得太慢。 一个成功的解决方案应该只处理每个单元恒定的次数，从而导致粗略的`O(nm)`工作。 

有几种边缘情况值得关注。 

考虑`k = 1`:```
2 2 1
..
..
```每个空单元格同时是有效的水平段和有效的垂直段。 正确答案是`4`， 不是`8`。 如果我们独立计算行和列，每个空单元格都会被计算两次。 

另一个重要的情况发生在空座位连续时间超过`k`。```
1 5 3
.....
```有效的段是：```
[1,2,3]
[2,3,4]
[3,4,5]
```答案是`3`。 粗心的实现可能每次运行只计算一个段。 

受阻的细胞分裂成独立的碎片。```
1 5 2
..*..
```左跑贡献一种排列，右跑贡献一种排列，总共`2`。 将整行视为一次运行会错误地产生`4`。 

## 方法

 最直接的解决办法就是暴力破解。 对于每个单元格，我们可以尝试开始一个水平长度段`k`并检查是否所有`k`单元格是空的。 我们可以在垂直方向上做同样的事情。 

这是正确的，因为每个可能的段都被检查一次。 问题是运行时间。 有`O(nm)`可能的起始位置，每次检查最多可检查`k`细胞。 在最坏的情况下，这会变成`O(nmk)`。 所有尺寸均达到`2000`，可以接近数十亿次操作。 

关键的观察是我们实际上并不关心单个细胞。 重要的是最大连续空座数。 

假设一行包含长度游程`L`。```
.....   (L = 5)
```如果我们需要`k = 3`，然后每个连续的长度块`3`这里面运行是有效的。 此类块的数量为：```
L - k + 1
```假如`L ≥ k`。 

我们不是单独检查每个候选段，而是扫描一次行，识别每个空运行，并立即添加其贡献。 同样的想法也适用于列。 

有一种特殊情况：`k = 1`。 

对于较大的`k`，水平和垂直段是不同的对象，因此独立计算行和列是正确的。 

为了`k = 1`，每个有效的排列都包含一个空单元格。 分别计算行和列会将每个空单元格计算两次。 在这种情况下，我们只需对空单元格计数一次然后停止。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nmk) | O(1) | O(1) | 太慢了|
 | 最佳| O(纳米) | O(1) 额外 | 已接受 |

 ## 算法演练

 1. 读取网格。 
2.如果`k = 1`，计算包含的单元格数量`.`并输出该值。 

每个空单元格都代表一种有效的排列。 分别计算行和列会重复计数。 
3. 从左到右扫描每一行。 

保持当前连续运行的空单元格的长度。 
4. 每当`*`遇到，则当前运行结束。 

如果游程长度是`L ≥ k`， 添加`L - k + 1`到答案，因为很多长度-`k`段适合运行。 
5. 完成该行后，以同样的方式处理最后的运行。 

行可能以空单元格结尾，因此最后一次运行需要单独处理。 
6. 对每一列重复相同的过程。 

每列都被视为一维序列。 每一次垂直奔跑都有贡献`L - k + 1`安排。 
7. 输出累计答案。 

### 为什么它有效

 每个有效的水平排列恰好属于空单元格的一个最大水平运行。 如果那次跑步有长度`L`，长度的可能起始位置`k`细分市场有：```
1, 2, ..., L-k+1
```这正好给出了`L-k+1`安排。 

该算法精确计算每次水平运行和每次垂直运行的排列。 不会错过任何有效的段，因为每个段都位于某个运行内。 没有段会被计数两次，因为一个段恰好有一个最大包含游程。 的特殊处理`k = 1`消除了水平和垂直计数重叠的唯一情况。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    if k == 1:
        ans = sum(row.count('.') for row in grid)
        print(ans)
        return

    ans = 0

    # Rows
    for r in range(n):
        run = 0
        for c in range(m):
            if grid[r][c] == '.':
                run += 1
            else:
                if run >= k:
                    ans += run - k + 1
                run = 0

        if run >= k:
            ans += run - k + 1

    # Columns
    for c in range(m):
        run = 0
        for r in range(n):
            if grid[r][c] == '.':
                run += 1
            else:
                if run >= k:
                    ans += run - k + 1
                run = 0

        if run >= k:
            ans += run - k + 1

    print(ans)

if __name__ == "__main__":
    solve()
```第一个分支处理特殊情况`k = 1`。 每个空单元格都是有效的排列，因此直接计算空单元格既简单又避免重复计算。 

行扫描将每一行视为一维数组。 变量`run`存储当前连续的空座位块的长度。 每当出现堵塞的座位时，运行就会结束并贡献`run - k + 1`如果其长度足够大，则分段。 

列扫描是相同的，只是索引是垂直遍历的。 

错误的常见来源是在完成一行或一列后忘记处理最终运行。 运行可能会持续到边界，因此贡献也必须在循环之后添加。 

另一个容易犯的错误是处理不当`k = 1`。 如果没有特殊分支，每个空单元格将在行扫描中计数一次，在列扫描中计数一次。

 ## 边缘情况

 ### 案例 1：`k = 1`输入：```
2 2 1
..
..
```算法立即进入特殊分支并对空单元进行计数。 有四个空单元格，所以答案是`4`。 

如果我们同时执行行和列扫描，每个单元格将在水平方向和垂直方向贡献一次，从而产生`8`，这是不正确的。 

### 情况 2：长时间空运行

 输入：```
1 5 3
.....
```行扫描找到具有长度的单个运行`5`。 

贡献是：```
5 - 3 + 1 = 3
```对应于起始位置 1、2 和 3。该算法对所有有效段进行计数，而不单独枚举它们。 

### 情况 3：障碍导致跑步中断

 输入：```
1 5 2
..*..
```扫描发现两个独立的长度游程`2`。 

第一次运行贡献：```
2 - 2 + 1 = 1
```第二次运行贡献了另一个`1`。 

总答案：```
1 + 1 = 2
```障碍物会阻止路段穿过中间位置，并且算法自然会通过每当出现障碍物时终止当前运行来强制执行此操作。`*`遇到。
