 ## 解决方案
 ## 问题理解

 我们有四名球员，分成两队，每队两人。 每个玩家都有两种独立的优势：一种是防守，一种是进攻。 比赛前，每队指定一名球员进攻，另一名球员防守。 

一旦分配确定，球队将通过两个数字进行评估：其防守值是防守者的防守技能，其攻击值是攻击者的攻击技能。 如果一支球队的防守严格大于对手的进攻，并且同时其进攻严格大于对手的防守，则认为一支球队严格强于另一支球队。 

交互是顺序的。 第一个团队首先宣布其角色分配。 在看到这个确切的任务并了解所有技能后，第二个团队会选择最佳的自己的任务。 我们想要确定第一队是否可以不管第二队的反应而强行获胜，第二队是否可以无论第一队的选择如何强行获胜，或者双方是否都没有强制获胜策略。 

限制非常小：只有四名玩家，每个团队只有两种可能的角色分配。 这立即排除了除了持续或微小的组合检查之外的任何事情。 甚至一个$O(1)$解决方案可以显式枚举所有配置。 

主要的微妙之处在于，“保证获胜”并不是指一场有利的比赛。 它需要一个团队分配来击败对手的所有可能的反应。 

一个常见的错误是将问题视为每个团队独立选择两个内部交换中更好的一个。 但这失败了，因为第二个团队在看到第一个团队的决定后做出了反应。 

另一个错误是对称地比较团队并通过单一的“最佳配置”比较来决定获胜者。 选择的顺序很重要：第一个团队做出承诺，第二个团队适应。 

暴露错误推理的边缘案例包括两支球队都有强大球员但交换角色却改变了结果的情况。 例如，如果球队 1 拥有球员 (1,100) 和 (100,1)，它可能看起来是对称的，但根据分配，一种配置是严格占主导地位的，而另一种配置则不是。 天真的“总和或最大比较”方法会错过该结构。 

## 方法

 每个团队都有两种可能的角色分配：玩家 1 进攻，玩家 2 防守，或者反过来。 这仅给出了游戏的四个全局状态。 

暴力方法会枚举所有可能性：对于团队 1 的每项任务，模拟团队 2 的两项任务并检查结果。 对于每场模拟比赛，我们都会评估定义胜利的两个严格的不平等。 这是每个状态的恒定工作，因此整个解决方案在实践中是恒定的时间。 

关键的观察结果是，该问题是一个具有完美信息且没有随机性的两步博弈。 由于每个玩家只有两个选择，因此除了直接枚举之外，我们可以完全解析博弈树，而无需任何极小极大机制。 我们不需要递归或DP，因为分支因子和深度都固定为2。 

我们不考虑博弈论抽象，而是直接测试主导地位。 如果 A 队的固定任务击败了 B 队的两种可能的反应，那么它就是“获胜策略”。对于 B 队来说也是如此。 

这将整个问题简化为检查恒定数量的成对比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力枚举| O(1) | O(1) | O(1) | O(1) | 已接受 |
 | 最佳直接检查 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将第 1 队的球员标记为 0 和 1，将第 2 队的球员标记为 2 和 3。 

每个团队可以选择两项任务中的一项。 我们明确计算每个任务的结果（攻击，防御）对。 

1. 为球队 1 构建两种可能的配置。一种配置使用玩家 0 作为攻击者，玩家 1 作为防御者，另一种配置交换角色。 对于每个配置，我们存储结果对（攻击、防御）。 我们这样做的原因是为了减少重复索引并使比较更明确。 
2. 以相同的方式构建团队 2 的两种可能的配置。 同样，我们产生两对（攻击、防御）。 
3. 对于每个团队 1 配置，检查它是否优于团队 2 配置。 胜利意味着严格的不平等：team1_def >对手_攻击和team1_attack >对手_def。 如果两个对手的配置都被击败，那么第 1 队可以通过选择此任务来强制获胜。 
4. 对称地，对于每个团队 2 配置，检查它是否击败两个团队 1 配置。 如果存在这样的配置，则 2 队强制获胜。 
5. 如果双方都没有一个配置能够击败对方的所有反应，则结果为平局。 

其核心思想是“保赢”相当于存在对对手整个响应集的支配配置。 

### 为什么它有效

 每个团队的策略空间恰好由两个状态组成。 第二支队伍总是在观察第一支队伍所选择的状态后做出反应，因此第二支队伍的最佳玩法始终是选择其两种配置中的任何一种能够产生胜利（如果存在）。

因此，一线队配置只有在对抗两种对手配置时都能生存下来才是安全的。 如果甚至有一个对手配置击败了它，第二支球队就可以选择该配置并使保证无效。 

由于两支球队在结构上是对称的，因此彻底检查两个方向涵盖了所有可能的比赛结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def parse_team(i1, i2, a, b):
    return [
        (b[i1], a[i2]),  # i1 attacks, i2 defends
        (b[i2], a[i1])   # i2 attacks, i1 defends
    ]

def beats(att_a, def_a, att_b, def_b):
    return def_a > att_b and att_a > def_b

a = []
b = []
for _ in range(4):
    x, y = map(int, input().split())
    a.append(x)
    b.append(y)

team1 = parse_team(0, 1, a, b)
team2 = parse_team(2, 3, a, b)

team1_win = False
team2_win = False

for att1, def1 in team1:
    ok = True
    for att2, def2 in team2:
        if not beats(att1, def1, att2, def2):
            ok = False
            break
    if ok:
        team1_win = True

for att2, def2 in team2:
    ok = True
    for att1, def1 in team1:
        if not beats(att2, def2, att1, def1):
            ok = False
            break
    if ok:
        team2_win = True

if team1_win and not team2_win:
    print("Team 1")
elif team2_win and not team1_win:
    print("Team 2")
else:
    print("Draw")
```该实现明确地为每个团队构造了两种可能的状态，这避免了重复重新计算角色交换。 这`beats`函数编码了定义胜利的两个严格条件。 

一个常见的实施陷阱是在交换角色时混淆攻击和防御。 将配置存储为（攻击、防御）对可以立即消除歧义并保持比较的一致性。 

## 工作示例

 ### 示例 1

 输入：```
1 100
100 1
99 99
99 99
```球队 1 有球员 (1,100) 和 (100,1)，所以它的两个配置是：

 | 步骤| 第 1 队进攻 | 第 1 队防守 |
 | ---| ---| ---|
 | 配置A| 100 | 100 100 | 100
 | 配置B | 1 | 1 |

 团队 2 的配置是相同的：两者的产量都是 (99,99)。 

检查配置 A：它击败 (99,99)，因为 100 > 99 且 100 > 99。由于两个团队 2 的配置相同，因此这就足够了。 

因此，团队 1 的配置主导所有响应。 

输出是：```
Team 1
```这证实了一个不变量：一种主导配置足以强制获胜。 

### 示例 2

 输入：```
5 1
1 5
4 4
4 4
```团队 1 配置：

 | 配置| 攻击| 国防 |
 | ---| ---| ---|
 | 一个 | 1 | 1 |
 | 乙| 5 | 5 |

 团队 2 的配置均为 (4,4)。 

配置 B 击败 (4,4)，因此团队 1 可以强行获胜。 配置A并不重要。 

因此：

 | 团队| 有主宰配置吗？ |
 | ---| ---|
 | 团队 1 | 是的 |
 | 团队 2 | 没有 |

 输出：```
Team 1
```这个例子表明只需要一项强大的配置； 较弱的内部互换是无关紧要的。

 ## 边缘情况

 一个关键的边缘情况是球队中的两名球员实力相同。 例如：```
10 10
10 10
5 5
5 5
```团队 1 配置相同，团队 2 配置也相同。 比较简化为单一匹配。 该算法正确地发现任何一方都没有严格的优势并输出平局。 

另一种情况是，当一支球队的进攻能力很强但防守能力很弱时，另一支球队总是可以反映出这个弱点。```
1 100
100 1
50 60
60 50
```第 1 队有获胜配置，但只有其中一个交换有效。 该算法会检查两者并正确识别出只有一种配置必须在所有对手响应中幸存下来。 

最后一个微妙的情况是，第二队只有在观察第一队的选择后才能获胜。 对两个团队 1 配置的枚举可确保即使一种配置易受攻击而另一种配置安全，该决策也反映是否存在强制胜利，而不是平均或最佳情况结果。
