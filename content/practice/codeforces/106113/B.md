 ## 解决方案
 ## 问题理解

 鲍勃想通过城市网络传播信息。 城市是无向图的顶点，边意味着信息可以在一周内在两个相邻城市之间移动。 

鲍勃不需要访问每个城市。 他只有两个可能的探访令。 在第一个顺序中，他访问具有奇数指数的城市，从较小的指数到较大的指数。 在第二个顺序中，他访问指数从小到大的偶数城市。 一周访问过的城市`k`成为该周传播信息的另一个起点。 接下来的每一周，知情的选民都会将这一信息传递给他们的邻居。 

任务是选择两种策略中较好的一种，并输出每个城市都知道该消息所需的周数。 如果这两种策略最终都无法覆盖每个城市，那么答案是`-1`。 

重要的观察是，稍后访问的城市仍然有用。 例如，几周后访问断开连接的组件允许消息从那里开始，即使无法从之前的访问中访问该组件。 

该图最多可以包含`100000`城市，因此每周模拟并反复传播信息的方法成本太高。 对于这个尺寸，我们需要大致线性或`O((n+m) log n)`工作。 运行一次或两次图遍历是可以接受的，但每次访问后都进行单独的遍历则不行。 

有一些边缘情况很容易破坏实现。 如果只有一个城市，答案是`1`因为鲍勃必须访问一次。```
Input:
1 0
```正确的输出是：```
1
```一种仅从现有边缘启动 BFS 或假设至少一个邻居会失败的解决方案。 

另一种情况是一个策略从不访问断开连接的组件。 例如：```
Input:
4 1
1 2
```仅使用奇数城市访问`1`和`3`，所以城市`3`和`4`只有在这些访问中接触到他们时才能得到覆盖。 城市`4`被隔离，永远不会收到消息。 对于均匀策略也可能会出现同样的问题。 答案是`-1`如果这两种策略都没有覆盖所有城市。 

最后一个微妙的情况是访问时间很重要。 一周访问过的城市`3`一周前无法传播信息`3`。 将所有访问过的城市视为每周都有空`1`给出了错误的结果。 

## 方法

 直接的解决方案是每周模拟一次活动。 对于选定的策略，我们知道鲍勃每周访问哪个城市。 每次访问后，我们可以对所有当前已获知信息的城市运行 BFS，并检查整个图是否被覆盖。 这是正确的，因为它遵循声明中描述的确切过程。 

问题是相同的边会被探索很多次。 在最坏的情况下，鲍勃会访问大约`n/2`城市和 BFS 成本`O(n+m)`。 总工作量大致为`O(n(n+m))`，这远远超出了可能的范围`n = 100000`。 

关键的观察是，整个过程可以被视为具有延迟起点的最短路径。 

如果鲍勃访问城市`u`一周内`t`，那么该城市可以通知另一个城市`v`在：```
t + shortest_distance(u, v)
```几周。 

对于固定策略，每个访问的城市都是一个具有不同开始时间的源。 我们需要所有来源中最短的到达时间。 这正是一个所有边都有权重的最短路径问题`1`，但每个源都以自己的初始距离开始。 我们可以通过使用优先级队列的多源 BFS 风格遍历来解决它。 

对于奇数城市，城市`i`一周内被访问`(i+1)/2`。 甚至对于城市、城市`i`一周内被访问`i/2`。 我们用所选策略中的所有城市及其访问周数初始化优先级队列，然后传播最早可能的到达时间。 

相同的算法可以处理这两种策略。 我们只需要运行两次并取较小的有效答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n(n+m)) | O(n(n+m)) | O(n+m) | 太慢了 |
 | 最佳 | O((n+m) log n) | O((n+m) log n) | O(n+m) | 已接受 |

 ## 算法演练

 1. 构建城市图的邻接表。 每条边都在两个方向上存储，因为信息可以双向传播。 
2、奇数城市策略解决一次问题。 将每个奇数城市放入优先队列，以其访问周为初始到达时间。 
3. 运行最短路径遍历。 每当一个城市有到达时间`t`从队列中删除，尝试提高每个邻居的时间`t+1`。 如果这给出了更好的时间，请更新邻居并将其推入队列。 
4、遍历结束后，找到所有城市中最大的到达时间。 如果某个城市仍然有无限的到达时间，则该策略无法告知整个图。 
5. 对偶数城市策略重复相同的过程。 唯一的区别是分配给每个源城市的初始周。 
6. 返回两种策略中较小的有效结果。 如果两种策略均失败，则返回`-1`。 

为什么它有效：

 对于固定策略，每个访问过的城市都是消息可能的起点。 优先队列算法始终保留每个城市可以获知信息的最小已知周。 由于每条边都恰好增加一周，因此松弛步骤会考虑来自每个源的每条可能的路径。 每个城市的最终值是以下所有可能访问过的城市中的最小值：```
visit_week + graph_distance
```这正是该市最早可以收到消息的一周。 取这些值中的最大值即可得出最后一个城市收到通知的周数。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve_strategy(n, graph, start_parity):
    inf = 10**18
    dist = [inf] * (n + 1)
    pq = []

    for city in range(1, n + 1):
        if city % 2 == start_parity:
            week = (city + 1) // 2 if city % 2 == 1 else city // 2
            dist[city] = week
            heapq.heappush(pq, (week, city))

    while pq:
        time, u = heapq.heappop(pq)

        if time != dist[u]:
            continue

        for v in graph[u]:
            if dist[v] > time + 1:
                dist[v] = time + 1
                heapq.heappush(pq, (dist[v], v))

    ans = max(dist[1:])
    if ans == inf:
        return -1
    return ans

def main():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        graph[u].append(v)
        graph[v].append(u)

    odd = solve_strategy(n, graph, 1)
    even = solve_strategy(n, graph, 0)

    if odd == -1:
        print(even)
    elif even == -1:
        print(odd)
    else:
        print(min(odd, even))

if __name__ == "__main__":
    main()
```功能`solve_strategy`包含整个图算法。 它是`start_parity`参数决定鲍勃访问哪些城市。 初始距离数组不是正常的 BFS 初始化，因为每个源都有不同的起始时间。 一周访问过的城市`k`从距离开始`k`， 不是`0`。 

由于初始值不同，因此使用优先级队列代替普通队列。 当所有源同时开始时，正常的 BFS 就会起作用，但这里一周访问过一个城市`1`必须始终在一周内访问之前进行处理`20`如果两者都在等待扩展。 

过时条目检查：```
if time != dist[u]:
    continue
```是必要的，因为一个城市在找到更好的路径后可以多次插入队列。 只有最新的最短值才应该扩展。 

最终的最大到达时间是一种策略的答案。 如果它保持无限，则该策略中任何访问过的城市都无法到达某个城市。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O((n+m) log n) | O((n+m) log n) | 每个城市和边缘都通过两种策略的优先级队列遍历进行处理。 |
 | 空间| O(n+m) | 邻接表存储图形，数组存储到达时间。 |

 约束允许这种复杂性，因为该图仅被遍历两次。 该算法避免了每次 Bob 访问后重复 BFS。

import sys
import io
import heapq

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    def solve_strategy(n, graph, parity):
        inf = 10**18
        dist = [inf] * (n + 1)
        pq = []

        for i in range(1, n + 1):
            if i % 2 == parity:
                t = (i + 1) // 2 if i % 2 else i // 2
                dist[i] = t
                heapq.heappush(pq, (t, i))

        while pq:
            t, u = heapq.heappop(pq)
            if t != dist[u]:
                continue
            for v in graph[u]:
                if dist[v] > t + 1:
                    dist[v] = t + 1
                    heapq.heappush(pq, (t + 1, v))

        return -1 if max(dist[1:]) == inf else max(dist[1:])

    n, m = map(int, input().split())
    graph = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        graph[u].append(v)
        graph[v].append(u)

    a = solve_strategy(n, graph, 1)
    b = solve_strategy(n, graph, 0)

    if a == -1:
        ans = b
    elif b == -1:
        ans = a
    else:
        ans = min(a, b)

    sys.stdin = old_stdin
    return str(ans) + "\n"

 ## 边缘情况

 对于单个城市：```
Input:
1 0
```奇怪的策略访问城市`1`一周内`1`。 到达数组变为`[1]`，所以最大到达时间为`1`。 该算法从不依赖于边缘，因此它直接处理这种情况。 

对于断开连接的图：```
Input:
4 1
1 2
```奇怪的策略从城市开始`1`和`3`。 城市`4`是孤立的，不是起始城市，所以它的距离保持无限。 均匀策略从城市开始`2`并且仅到达第一个组件。 也离开了城市`4`无法到达。 由于两种策略都包含无限的到达时间，所以答案是`-1`。 

对于延迟访问：```
Input:
5 4
1 2
2 3
3 4
4 5
```均匀策略访城`2`一周内`1`和城市`4`一周内`2`。 城市`5`从城市可以到达`4`一周内`3`，这比等待奇策访问城市要早`5`一周内`3`。 优先级队列将这些不同的开始时间分开，因此它不会错误地假设每个源在一周内都存在`1`。
