 ## 解决方案
 ## 问题理解

 我们有一棵树$n$顶点和$n-1$边缘。 每条边都必须分配一个公司编号。 如果一个城市的所有道路都属于不同的公司，则该城市被认为是“好”的。 如果至少两条事故道路受到同一公司的袭击，一座城市就会变得_糟糕_。 

我们最多可以拥有$k$糟糕的城市。 在所有有效的分配中，我们必须尽量减少公司的数量$r$。 找到尽可能小的值后$r$，我们还需要使用来自的公司编号输出一种有效的边缘颜色$1$到$r$。 

该图是一棵树，这意味着每对顶点之间都存在一条简单路径。 输入给出每条道路的端点，输出必须为每条道路分配一个公司编号。 

限制才是真正的挑战。 该树最多可以包含$200\,000$顶点，因此任何重复扫描所有顶点或尝试许多候选着色的算法都太昂贵了。 只有两秒的时间，预期的解决方案必须接近线性或$O(n \log n)$。 

关键的困难在于，最小化公司数量并不是直接影响整个树的着色问题。 我们最多可以违反不同颜色条件$k$顶点。 了解应该牺牲哪些顶点是主要的见解。 

考虑以顶点 1 为中心的星形：```
1-2
1-3
1-4
1-5
```和$k=1$。 

中心的度数为 4。如果我们允许顶点 1 为坏点，则所有边都可以使用相同的颜色，并且$r=1$。 盲目地尝试使每个顶点都良好的解决方案会错误地得出需要四种不同颜色的结论。 

另一个微妙的情况是路径：```
1-2-3-4-5
```和$k=0$。 

每个顶点的度数最多为 2。答案不是 2，因为树的正确边缘着色只需要$\Delta$颜色，哪里$\Delta$是最大程度。 这里$\Delta=2$，并且沿路径交替颜色有效。 任何假设每条边都必须具有唯一颜色的实现都会高估答案。 

当许多顶点共享相同度数时，就会出现第三个陷阱。 假设度数是：```
5, 5, 5, 1, 1, ...
```和$k=2$。 

我们可以选择任意两个 5 度顶点来变坏。 答案取决于第三大度，而不取决于选择了哪些特定顶点。 错误处理等度的实现可能会产生大于必要的值$r$。 

## 方法

 蛮力观点是猜测公司的数量$r$，然后尝试确定树是否最多可以被着色$r$最多制作时的颜色$k$顶点不好。 

这很快就变得不可行。 甚至检查单个值$r$通过探索可能的边缘着色具有巨大的搜索空间。 一棵树与$200\,000$顶点已经包含$199\,999$边缘，因此任何组合搜索都是没有希望的。 

转折点来自于询问是什么迫使大量颜色出现。 

如果顶点必须保持良好状态，则所有入射边都需要不同的颜色。 度数的顶点$d$立即至少需要$d$可用颜色。 

现在假设我们认为某个顶点可能是坏的。 然后我们不再关心入射边是否在那里重复颜色。 

这一观察彻底改变了问题。 唯一强制使用大量颜色的顶点是我们选择保持良好状态的顶点。 

假设度数按降序排列：$$d_1 \ge d_2 \ge \cdots \ge d_n.$$我们最多可以牺牲$k$顶点。 当然，我们应该牺牲度数最大的顶点，因为它们对颜色的要求最强。 

删除那些之后$k$最坏的约束，最小必要的颜色数量变成$$r = d_{k+1}.$$如果$k=0$，这就是最大程度。 如果$k=n-1$，除了一个之外的每个顶点都可能是坏的，所以$r=1$。 

剩下的任务是建设性的：精确地使用$r$颜色。 

标准树边缘着色 DFS 在这里完美运行。 我们在遍历时给树扎根并给边缘着色。 在度数超过的顶点$r$，我们故意允许重复。 在每个其他顶点，我们为所有入射边分配不同的颜色。 

因为$r$等于$(k+1)$-最大程度，最多有$k$度数超过的顶点$r$。 那些成为坏顶点。

 ## 算法演练

 1. 读取树并计算每个顶点的度数。 
2. 将所有学位按降序排序。 
3.让$r$成为$(k+1)$-最大程度。 在从零开始的索引中，这是`sorted_deg[k]`。 

该值是可能的最小颜色数，因为至少$n-k$顶点必须保持良好，并且每个良好的度顶点$d$需要$d$不同的颜色。 
4. 在任意顶点处建立树的根，例如顶点 1。 
5. 执行 DFS。 
6. 假设连接当前顶点与其父顶点的边有颜色`parent_color`。 
7. 对于当前顶点的子节点，从 1 到$r$, 跳过`parent_color`。 

这保证了只要度数不超过该顶点的所有入射边都会收到不同的颜色$r$。 
8. 如果颜色计数器超过$r$，将其重新包装回 1。 

这种包裹只能在度数超过的顶点处创建重复的颜色$r$。 这些正是我们愿意破坏的顶点。 
9. 通过原始输入索引存储为每个边缘分配的颜色。 
10. 输出$r$和所有边缘颜色。 

### 为什么它有效

 关键的属性是每个顶点的度数最多$r$在所有入射边缘上接收成对不同的颜色。 

在这样的顶点，一种颜色已经被其父级的边缘占据。 DFS 为所有子边缘分配不同的颜色，同时跳过父颜色。 由于入射边的总数不超过$r$，有足够的颜色可用并且不会发生重复。 

仅当顶点的度数大于$r$。 这样的顶点数量最多为$k$， 因为$r$被选为$(k+1)$-最大程度。 因此至多$k$顶点变得不好。 

着色仅使用颜色$1 \ldots r$，满足坏顶点限制，并且$r$是最小的。 因此该算法是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())

    g = [[] for _ in range(n)]
    deg = [0] * n
    edges = []

    for idx in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1

        edges.append((u, v))

        g[u].append((v, idx))
        g[v].append((u, idx))

        deg[u] += 1
        deg[v] += 1

    sorted_deg = sorted(deg, reverse=True)
    r = sorted_deg[k]

    ans = [0] * (n - 1)

    stack = [(0, -1, 0)]

    while stack:
        v, parent, parent_color = stack.pop()

        color = 1

        for to, eid in g[v]:
            if to == parent:
                continue

            if color == parent_color:
                color += 1

            if color > r:
                color = 1

            ans[eid] = color

            stack.append((to, v, color))

            color += 1
            if color > r:
                color = 1

    print(r)
    print(*ans)

if __name__ == "__main__":
    main()
```第一部分构建邻接表并计算顶点度数。 

排序后的度数组仅使用一次。 位置处的值`k`正是$(k+1)$-最大程度，即最佳颜色数。 

DFS 是迭代的而不是递归的。 递归解决方案可以溢出 Python 对树的递归限制$200\,000$顶点。 

变量`parent_color`记录通向当前顶点的边的颜色。 为子边缘分配颜色时，只要有可能就会跳过该颜色。 这保证了低度顶点的不同入射颜色。 

环绕行为是有意的。 一旦一个顶点有超过`r`事件边缘，重复变得不可避免。 这些顶点正是我们可以牺牲的顶点。

 ## 边缘情况

 考虑明星```
5 1
1 2
1 3
1 4
1 5
```度数顺序为$[4,1,1,1,1]$。 第二大度是 1，所以$r=1$。 中心是唯一度数超过的顶点$r$，这是允许的，因为$k=1$。 每条边都接收颜色 1。坚持每个顶点都有不同颜色的解决方案将错误地输出 4。 

考虑路径```
5 0
1 2
2 3
3 4
4 5
```度数顺序为$[2,2,2,1,1]$。 由于不允许有坏顶点，$r=2$。 在 DFS 过程中，颜色自然交替，每个顶点都会看到不同的入射颜色。 该算法绝不会引入不必要的颜色。 

考虑一棵三个最大度数相等的树：```
7 2
1 2
1 3
1 4
5 1
6 1
7 1
```度数顺序为$[6,1,1,1,1,1,1]$。 和$k=2$，答案变为第三大度数，仍然是 1。该算法仅依赖于排序顺序，因此关系会自动处理，无需特殊逻辑。 

最后，当$k=n-1$，除了一个顶点之外的每个顶点都可能是坏的。 排序后的度数索引`k`总是存在，因为数组有长度$n$。 答案变为 1，将每条边着色为颜色 1 是有效的。 该实现在没有任何分支的情况下处理这种情况。
