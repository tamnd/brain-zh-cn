 ## 解决方案
 ## 问题理解

 我们从一个数字开始，并希望达到更大的目标数字。 唯一允许的操作是将当前值乘以`2`或通过`3`。 任务是确定需要多少操作，或者报告转换无法完成。 

思考该过程的一个有用方法是查看起始值和目标值之间的变化。 每一步都只会引入额外的因素`2`或者`3`。 任何其他东西都不会出现。 如果目标除以下之外还包含任何额外的质因数`2`和`3`, relative to the starting number, the transformation is impossible.

 数字最多为`5 × 10^8`，它足够小，可以重复除以`2`和`3`非常便宜。 即使在最坏的情况下，数字也低于`5 × 10^8`包含少于三十个因子`2`且少于二十个因数`3`，所以一个简单的循环就足够了。 

一些边缘情况值得关注。 

假设起始值和目标值已经相等。 

输入：```
10 10
```输出：```
0
```无需任何操作。 总是执行至少一次乘法的解决方案在这里会失败。 

假设目标不是起始值的倍数。 

输入：```
48 72
```输出：```
-1
```由于每次操作仅乘以当前值，因此我们永远无法减少或删除因子。 如果`m`不能被整除`n`，达到这个目标是不可能的。 

假设该比率包含除`2`或者`3`。 

输入：```
4 20
```输出：```
-1
```比例为`20 / 4 = 5`。 乘以`2`和`3`永远不能创造一个因素`5`。 

## 方法

 蛮力的观点是将每个数字视为一个状态并反复尝试乘以`2`和`3`直到达到目标。 广度优先搜索最终会找到答案，因为每条边都代表一次移动。 

问题是数值范围很大。 尽管目标只是`5 × 10^8`，探索所有可达状态是不必要的工作。 状态图随着移动次数呈指数增长，并且通用搜索比所需的复杂得多。 

关键的观察结果是，每个有效的操作序列都会将起始数乘以以下幂的某种组合：`2`和`3`。 

如果$$m = n \cdot 2^a \cdot 3^b,$$那么正是`a + b`需要移动。 每次乘以`2`贡献了一个因素`2`，并且每次乘以`3`贡献了一个因素`3`。 

这立即将问题简化为分析比率$$r = \frac{m}{n}.$$如果`m`不能被整除`n`，无解。 

否则，重复划分`r`经过`2`尽可能并计算它发生的次数。 然后做同样的事情`3`。 如果除此之外还剩下什么`1`，该比率包含一些其他素因数，使得转换不可能。 如果剩余值为`1`，答案就是执行的除法总数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 移动次数呈指数级增长 | 指数| 太慢了 |
 | 最佳 | O(log(m/n)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`n`和`m`。 
2. 检查是否`m`可以整除`n`。 

如果没有，则输出`-1`因为乘法永远无法消除目标比率中已经存在的因素。 
3. 计算`r = m // n`。 

该比率代表必须通过乘法相加的所有内容`2`和`3`。 
4. 初始化`moves = 0`。 
5. 虽然`r`可以整除`2`，除以`2`并增加`moves`。 

每个除法对应于一次乘法`2`在前进的过程中。 
6. 虽然`r`可以整除`3`，除以`3`并增加`moves`。 

每个除法对应于一次乘法`3`。 
7. 检查剩余价值`r`。 

如果`r != 1`，除`2`或者`3`仍然存在，所以输出`-1`。 
8.否则输出`moves`。 

### 为什么它有效

 比率`m / n`准确捕捉达到目标所需的乘法变化。 每个允许的操作都会影响其中一个因素`2`或者`3`，因此任何可达比率必须具有以下形式`2^a 3^b`。 

该算法消除了所有因素`2`和`3`从比例来看。 如果什么都没有剩下，那么这个比例就是`2^a 3^b`， 和`a + b`操作既是必要的也是充分的。 如果某些因素仍然存在，则永远无法使用允许的操作创建它，从而使转换变得不可能。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    if m % n != 0:
        print(-1)
        return

    r = m // n
    moves = 0

    while r % 2 == 0:
        r //= 2
        moves += 1

    while r % 3 == 0:
        r //= 3
        moves += 1

    if r != 1:
        print(-1)
    else:
        print(moves)

solve()
```第一个检查验证目标是否是起始值的倍数。 如果没有这个条件，整数除法就会隐藏不可能的情况。 

变量`r`存储仍需要由允许的操作解释的比率。 每次我们除以`2`或者`3`，我们计算一个相应的移动。 

最后的检查至关重要。 去除所有因素后`2`和`3`，剩余值必须恰好是`1`。 如果不是，则仍然存在一些禁止的素因数。 缺少此检查将错误地接受诸如`4 → 20`，其中比率为`5`。 

所有算术都在 Python 整数范围内，并且循环仅执行对数次数。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(log(m/n)) | 每次迭代都会从比率 | 中删除 2 或 3 个因子。

 ## 边缘情况

 考虑数字已经相等的情况。 

输入：```
10 10
```比例为`1`。 两个除法循环都不执行。 该算法达到最终检查`r = 1`和输出`0`。 这正确地反映了不需要任何操作。 

考虑一个不能被起始值整除的目标。 

输入：```
48 72
```第一个检查计算`72 % 48`，它不为零。 算法立即输出`-1`。 任何乘法序列都可以被原始值整除，因此达到`72`从`48`是不可能的。 

考虑包含另一个素因数的比率。 

输入：```
4 20
```比例为`5`。 它不能被整除`2`或者`3`，所以两个循环都不会运行。 剩余价值仍为`5`， 不是`1`，算法输出`-1`。 这正确地拒绝了需要引入除`2`或者`3`。
