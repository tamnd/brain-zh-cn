 ## 解决方案
 ## 问题理解

 我们得到一个代表一天的二进制序列，其中每个位置对应一个小时。 值为`1`意味着波利卡普在那段时间正在休息，而`0`意味着他正在工作。 相同的序列永远重复，因此在一天的最后一个小时之后，下一小时又是同一时间表的第一个小时。 

任务是确定如果允许我们跨越一天结束和下一天开始之间的界限，最长的不间断休息时间。 

一个关键点是该序列是循环的。 从数组末尾附近开始的任何段都可以在开头继续，就好像数组在循环中端到端连接一样。 

输入大小可达200​​,000小时。 这排除了任何试图检查每个可能的起始位置并向外扩展的解决方案，因为这在最坏的情况下会导致二次行为。 线性扫描是唯一现实的目标。 

当人们将数组视为线性并忽略环绕时，就会发生天真的错误。 例如，在`1 1 0 1 1 1`，正确答案是 4，因为运行`1 1`最后连接到`1 1 1`一开始。 线性扫描会错误地报告 3。 

另一种常见的边缘情况是数组除了单个值之外全部为零。 正确答案是 0，因为没有休息时间，并且天真的循环合并策略可能会错误地将间隙视为休息。 

## 方法

 暴力解决方案将在每个开始小时尝试并在遇到问题时向前延伸`1`s，使用模算术进行环绕。 对于每个起始位置，我们走到`n`步骤。 这会产生一个`O(n^2)`最坏情况下的算法，因为每个起点可能几乎遍历整个数组。 和`n = 2 * 10^5`，这太慢了。 

问题的结构建议采用循环数组，目标是找到最长的连续块`1`s 在一个圆圈上。 循环序列的标准技巧是复制数组，将环绕段转换为正常的连续段。 

如果我们建造`a + a`，任何跨越原始数组边界的段都会成为双倍数组中的正常段。 唯一需要注意的是有效段不能超过长度`n`，因为我们仍然代表当天的一整轮循环。 

所以问题就简化为寻找最大连续数`1`s 在双倍数组中，同时确保我们计数的数量不超过`n`元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 最佳（圆形倍频/线性扫描）| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取长度的数组`n`。 我们将其视为循环，即索引`n - 1`连接回索引`0`。 
2.创建一个新数组`b`这是`a`与自身连接。 这会将圆形邻接转换为正常邻接，因此环绕序列变成直线段。 
3.初始化两个变量：`best = 0`存储最大连续数，并且`current = 0`扫描时跟踪当前条纹长度。 
4. 迭代中的每个元素`b`从左到右。 

如果当前元素是`1`, 增量`current`增加一，因为连胜仍在继续。 如果是的话`0`， 重置`current`归零，因为连胜被打破了。 
5.更新后`current`， 更新`best`作为`max(best, current)`。 
6. 如果`current`超过`n`，将其夹回`n`。 这可以防止对跨越原始一天的一个完整周期的分段进行计数。 
7. 继续直到结束`b`。 最终的答案是`best`。 

### 为什么它有效

 原始数组中连续的每个有效圆弧段与双倍数组中的某个连续圆弧段完全对应。 通过扫描双倍数组，我们隐式枚举所有可能的环绕段。 唯一的限制是我们不能使用超过`n`连续的元素，因为这意味着要遍历一天中的多个完整周期。 维护简单的运行计数可确保捕获每个最大块，并且重置为零可保证分段的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())
a = list(map(int, input().split()))

b = a + a

best = 0
current = 0

for i in range(len(b)):
    if b[i] == 1:
        current += 1
        if current > n:
            current = n
    else:
        current = 0
    best = max(best, current)

print(best)
```该实现直接遵循将圆形阵列转换为线性阵列的思想。 加倍步骤可确保自然处理环绕段。 

唯一的微妙之处是上限`n`，当加倍数组允许人为的长条纹时，这可以防止夸大运行。

def solve():
    import sys
    input = sys.stdin.readline
    n = int(input().strip())

    best = 0
    cur = 0

    for x in b:

 ## 边缘情况

 考虑输入`6 1 1 0 1 1 1`。 最佳片段从末尾绕到开头，给出五个连续的片段。 

在双倍数组中，我们看到`1 1 0 1 1 1 1 1 0 1 1 1`。 扫描从索引 0 开始连续扫描，达到长度 2，在 2 处中断，在 3 处重新开始，并通过边界增长，在索引 7 处达到 5。此时，`best`变为5并保持不变。 

这证实了无需显式模运算即可自然捕获环绕案例。
