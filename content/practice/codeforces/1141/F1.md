[CF 1141F1 - 相同求和块（简单）](https://codeforces.com/problemset/problem/1141/F1)

 **标签：** 贪婪
 **求解时间：** 1m 44s
 **已验证：** 否

 ## 解决方案
 ## 问题理解

 给定一个整数数组，我们可以选择几个连续的子数组，称为块。 每个选定的块必须具有完全相同的总和，并且两个选定的块不能重叠。 

在所有可能的总和中，我们想要允许最大数量的成对不相交块的总和。 找到最佳总和后，我们必须输出具有该总和的最大大小的块集合。 

关键细节是金额没有提前给出。 我们可以自由选择任何值，只要所有选定的块共享它即可。 

简单版本有$n \le 50$。 这立即改变了问题的性质。 子数组总数仅为$$\frac{n(n+1)}{2} \le 1275.$$这意味着我们可以显式生成每个子数组及其总和。 不可能的方法$n=10^5$在这里变得完全合理。 

一个常见的错误是只专注于查找具有相同总和的许多子数组。 这些块也必须是不相交的。 例如：```
3
1 1 1
```总和$2$出现在块中$(1,2)$和$(2,3)$，但是这些重叠，所以我们只能取其中之一。 

另一个简单的陷阱是假设更长的块在某种程度上更好。 考虑：```
4
1 1 1 1
```对于总和$2$，我们可以选择$(1,2)$和$(3,4)$，给出两个块。 对于总和$4$，我们只得到$(1,4)$，给出一个块。 目标是最大化块数量，而不是最大化覆盖长度。 

负数也很重要。 例如：```
4
1 -1 1 -1
```几个不同的子数组有和$0$。 任何依赖于积极性的解决方案，例如两指针，都会失败。 

## 方法

 最直接的想法是生成每个子数组，计算其总和，然后按该总和对子数组进行分组。 一旦我们确定了一个特定的金额$S$，问题就变成：

 > 在总和为的所有区间中$S$，选择不重叠间隔的最大数量。 

这就是经典的区间调度问题。 

对每个和的强力搜索可以尝试间隔的每个子集并检查它们是否重叠。 这显然是正确的，但即使每个总和只有几十个间隔，子集的数量也会呈指数增长。 

改变一切的观察结果是间隔调度有一个贪婪的解决方案。 如果所有间隔已经具有相同的总和，那么唯一重要的是最大化非重叠间隔的计数。 标准策略是按结束位置对间隔进行排序，并重复选取最后选择的间隔之后开始的第一个间隔。 

为什么这在这里有效？ 选择最早的完成间隔可以为以后的间隔留出尽可能多的空间。 这与经典最大非重叠区间问题中使用的论点完全相同。 

自从$n \le 50$，我们可以生成所有$O(n^2)$子数组，按总和分组存储它们，并为每个不同的总和独立运行间隔调度。 所有求和中最好的结果就是答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解总和子集 | 指数| 指数| 太慢了 |
 | 生成所有子数组+贪婪区间调度| O(n² log n) | O(n² log n) | O(n²) | 已接受 |

 ## 算法演练

 1. 枚举每个子数组$(l,r)$。 

使用前缀和或直接累加来计算每个子数组的和。 将间隔存储在与该总和关联的容器内。 
2. 对于每个不同的总和$S$，收集所有元素相加为的区间$S$。 

现在这个特定总和的问题与其他所有总和无关。 
3. 按右端点对这些区间进行排序。 

这是间隔调度使用的标准顺序。 
4. 从左到右扫描排序后的区间。 

跟踪最后选定间隔的结束位置。 
5. 每当最后选定的时间间隔结束后开始一个时间间隔时，请选择它。 

此间隔不能与任何先前选择的间隔重叠。 
6. 继续，直到处理完该总和的所有间隔。 

结果集是不相交间隔的最大尺寸集合，其总和$S$。 
7. 将其大小与目前找到的最佳答案进行比较。 

如果更大，则替换当前最佳答案。 
8. 检查所有和后，输出存储的最佳集合。 

### 为什么它有效

 固定任意金额$S$。 每个有效的解决方案$S$仅由总和等于的区间组成$S$。 在这些区间中，我们需要最大数量的成对不相交区间。 

这正是区间调度问题。 众所周知的贪婪规则总是采用最早完成位置的可用间隔，产生一组最佳的不重叠间隔的最大基数。 

由于我们独立计算每个可能总和的最佳集合，然后选择其中最大的一个，因此最终答案对于所有总和也是最佳的。 

## Python 解决方案```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    sums = defaultdict(list)

    for l in range(n):
        cur = 0
        for r in range(l, n):
            cur += a[r]
            sums[cur].append((l + 1, r + 1))

    best = []

    for intervals in sums.values():
        intervals.sort(key=lambda x: x[1])

        chosen = []
        last_end = 0

        for l, r in intervals:
            if l > last_end:
                chosen.append((l, r))
                last_end = r

        if len(chosen) > len(best):
            best = chosen

    print(len(best))
    for l, r in best:
        print(l, r)

if __name__ == "__main__":
    solve()
```第一个嵌套循环生成每个子数组。 自从$n$只有50个，存储所有$O(n^2)$间隔是完全安全的。 该变量不是从头开始重新计算总和`cur`将当前子数组一次扩展一个位置。 

字典`sums`按子数组和对间隔进行分组。 每个键代表一个候选公共和。 

对于每个组，间隔按其右端点排序。 贪婪扫描使用`last_end`记住最近选择的间隔的结束时间。 条件`l > last_end`保证严格的不重叠。 

间隔端点在生成后立即存储为基于 1 的索引。 这可以避免打印时出现任何后续转换错误。 

在 Python 中，整数溢出不是问题，但在具有固定宽度整数的语言中，总和应该以 64 位类型存储，因为块总和可能达到数百万的数量级。 

## 工作示例

 ### 示例 1

 输入：```
7
4 1 2 2 1 5 3
```sum 3 的相关区间为：

 | 间隔 | 总和 |
 | ---| ---|
 | (2,3) | 3 |
 | (4,5) | 3 |
 | (7,7) | 3 |

 按右端点排序后：

 | 步骤| 间隔 | 最后一个结束时间之前 | 选择了？ | 最后结束 |
 | ---| ---| ---| ---| ---|
 | 1 | (2,3) | 0 | 是的 | 3 |
 | 2 | (4,5) | 3 | 是的 | 5 |
 | 3 | (7,7) | 5 | 是的 | 7 |

 贪心算法获得三个不相交的区间。 没有其他的总和能产生超过三的结果，所以这就是答案。 

### 示例 2

 输入：```
4
1 1 1 1
```考虑总和 2。 

间隔：

 | 间隔 | 总和 |
 | ---| ---|
 | (1,2) | 2 |
 | (2,3) | 2 |
 | (3,4) | 2 |

 贪心扫描：

 | 步骤| 间隔 | 最后一个结束时间之前 | 选择了？ | 最后结束 |
 | ---| ---| ---| ---| ---|
 | 1 | (1,2) | 0 | 是的 | 2 |
 | 2 | (2,3) | 2 | 没有 | 2 |

此示例说明了为什么重叠处理至关重要。 三个区间具有相同的总和，但只有两个可以共存。

 ## 边缘情况

 考虑：```
3
1 1 1
```总和为 2 的区间为$(1,2)$和$(2,3)$。 它们在位置 2 处重叠。按右端点排序后，贪心算法取$(1,2)$。 当它达到$(2,3)$，条件`l > last_end`失败是因为`2 > 2`是假的。 只选择一个区间，这是最优的。 

现在考虑：```
4
1 1 1 1
```对于 sum 2，存在三个候选区间。 贪心扫描选择$(1,2)$, 跳过$(2,3)$，然后选择$(3,4)$。 答案大小变为 2。 一个粗心的实现，仅仅计算具有相同总和的间隔会错误地返回 3。 

最后，考虑：```
4
1 -1 1 -1
```间隔$(1,2)$和$(3,4)$两者的总和均为 0 并且不重叠。 尽管存在负数，该算法仍将它们分组在一起，然后间隔调度选择两者。 没有使用有关单调和或正值的假设，因此该方法仍然正确。
