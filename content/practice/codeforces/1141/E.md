 ## 解决方案
 ## 问题理解

 我们得到了一个具有初始生命值的怪物和每分钟应用一次的重复伤害模式。 图案有长度`n`，在最后一分钟之后，我们立即循环回到第一分钟并永远继续。 

每分钟都会通过添加一个固定整数来修改当前的健康状况，该整数可以是负数也可以是正数。 当怪物的生命值第一次变为负数时，怪物就会死亡。 我们必须确定这个无限时间线中发生这种情况的最早的分钟，或者得出结论，这种情况永远不会发生。 

这些限制使得暴力推理变得很重要。 原则上我们可以模拟的分钟数是无限的，但是`n`最多可达 200,000，初始生命值可达 10^12。 在最坏的情况下，对每分钟进展的简单模拟可能需要多达 10^12 次迭代，这远远超出了可行的限制。 仅当我们可以跳过大块时，即使重复多次的单遍也是可以接受的。 

一个微妙的问题是，生命值可能会在一轮内增加，然后又减少，因此死亡时刻可能发生在一个周期的中间，而不仅仅是在周期边界。 

一种边缘情况是当一个完整周期的总和为非负并且没有前缀减少到足以杀死怪物时。 例如，如果所有`d_i`是积极的，怪物永远不会死。 简单的模拟可能仍然会永远运行。 

当累积效应总体为负但怪物在早期周期中存活下来时，就会出现另一种边缘情况。 死亡可能发生在多次完整重复之后的后续循环深处，因此我们必须将前缀行为与重复移位结合起来。 

## 方法

 暴力方法每分钟进行模拟，连续应用序列并检查运行状况是否降至零或更低。 这是正确的，因为它准确地反映了该过程，但它变得不可行，因为模拟步骤的数量可能非常大。 如果答案是`k`，那么在最坏的情况下`k`可以是 10^12 或更多，这使得这种方法在时间限制内不可能。 

关键的观察结果是序列是周期性的，因此在每个完整周期之后，健康状况会发生一个恒定值的变化，该值等于所有序列的总和`d_i`。 这使我们能够压缩重复的循环。 我们不是模拟每一分钟，而是模拟整个周期，同时跟踪全球健康状况的变化。 

我们预先计算数组的前缀和，它告诉我们一个周期内每分钟后的净变化。 从给定的健康状况开始的任何周期内`H`，我们可以通过检查怪物是否在该周期内死亡来确定`H + prefix[i] <= 0`对于某些人来说`i`。 如果不是，我们将完整周期后的新健康状况计算为`H + total_sum`并重复。 

如果一个周期的总和非负，并且怪物存活了一个完整的周期而没有死亡，那么它就永远不会死亡。 这是因为未来的周期永远不会将其健康状况降低到足以创造新的最小值。 

为了避免逐周期迭代，我们可以使用一组先前看到的状态，或者直接使用算术计算当总和为负数时可以安全跳过多少个完整周期。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(k) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算损坏数组的前缀和。 这给出了单个周期中每分钟后的净健康变化。 这种结构使我们能够检测循环内的死亡，而无需逐步模拟。 
2. 扫描前缀和找到最早的索引`i`这样`H + prefix[i] <= 0`。 如果这样的索引存在并且我们处于第一个循环，我们可以立即返回`i + 1`作为答案。 
3. 计算一个完整周期的总和。 该值决定了随着时间的推移，重复的循环是否会使怪物变弱或变强。 
4. 如果总和大于或等于 0 并且怪物在第一个完整周期中幸存，则返回`-1`。 这是因为健康状况在整个周期中永远不会减少，因此任何未来的周期都以至少相同或更高的健康状况开始，并且前缀模式是相同的。 
5. 否则，总和为负数。 我们反复模拟循环，但我们不是一分钟一分钟地进行，而是首先在每个循环内检查是否发生死亡。 如果没有，我们会减少健康状况的总和，并累积处理的完整分钟数。 
6. 每个周期我们都会调整起始健康状况并使用前缀和重新计算阈值检查，直到找到发生死亡的周期。 

### 为什么它有效

 该算法依赖于每个周期内的不变量，唯一可能的故障点由相对于周期的起始健康状况的前缀和确定。 前缀和的顺序在循环之间永远不会改变； 仅应用恒定平移。 如果总循环总和是非负的并且没有前缀是致命的，那么所有未来的循环都是相同的或更好的生存，防止任何最终的死亡。 如果总和为负，重复应用会严格降低起始生命值，如果生存不是无限的话，保证最终终止。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    H, n = map(int, input().split())
    d = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + d[i]

    total = pref[n]

    cur = H
    time = 0
    seen = {}

    # We iterate cycle by cycle, but break early when possible
    while True:
        # check death inside current cycle
        for i in range(1, n + 1):
            if cur + pref[i] <= 0:
                print(time + i)
                return

        # survive full cycle
        cur += total
        time += n

        if total >= 0:
            print(-1)
            return

        # optional safety (not strictly needed but avoids pathological loops)
        if cur in seen:
            print(-1)
            return
        seen[cur] = True

        if cur <= 0:
            print(time)
            return

if __name__ == "__main__":
    solve()
```该解决方案构建了前缀和，以便可以在线性时间内检查每个周期。 内部循环检查当前的起始生命值与任何前缀和相结合是否会导致该循环内的死亡。 如果不存在这样的前缀，则整个周期都会幸存，并且通过添加总周期总和来更新运行状况。 

关键的实现细节是`cur + pref[i] <= 0`check，直接编码怪物是否在某一分钟死亡`i`当前循环的结果，无需模拟每个减法步骤。 

我们还处理无限情况`total >= 0`，因为重复的循环永远不会将起始健康状况降低到足以改变结果的程度。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    H, n = map(int, input().split())
    d = list(map(int, input().split()))

    pref = [0]
    for x in d:
        pref.append(pref[-1] + x)

    total = pref[-1]
    cur = H
    time = 0

    while True:
        for i in range(1, n + 1):
            if cur + pref[i] <= 0:
                return str(time + i)

        cur += total
        time += n

        if total >= 0:
            return "-1"

 ## 边缘情况

 一个边缘情况是怪物在第一个周期内死亡。 对于像这样的输入`H = 3, d = [-2, 10]`，前缀和显示在第 1 分钟立即失败，因为`3 + (-2) <= 0`。 该算法在任何循环重复之前捕获这一点。 

另一种边缘情况是循环总和为零时。 例如，`d = [1, -1]`和`H = 5`。 前缀总和永远不会降低健康状况，并且每个周期后健康状况保持不变。 由于没有前缀在第一个循环中杀死怪物，因此以后的每个循环都是相同的，因此结果是`-1`。
