 ## 解决方案
 ## 问题理解

 给定一个仅由字符 A 和 B 组成的二进制字符串。我们的任务是在涉及回文的特定结构条件下计算其连续子串中有多少是“好”的。 

如果子串内的每个位置都属于至少一个长度严格大于完全包含在该子串中的回文串，则该子串被认为是好的。 换句话说，子字符串中的每个字符都必须被完全位于同一子字符串内的一些不平凡的回文（长度至少为 2）“覆盖”。 

关键的困难在于，这不是问子串本身是否是回文，而是问它是否可以被分解或被重叠的回文结构覆盖，以便没有一个字符被孤立。 

约束允许字符串长度最大为 300,000。 在最坏的情况下，对所有子串进行二次扫描将产生大约 4.5e10 个子串，这使得任何显式检查每个子串的方法都不可行。 即使在线性时间内检查每个子串仍然太慢。 

这将我们推向 O(n log n) 或 O(n) 策略，其中子字符串不是独立检查的，而是在聚合范围内贡献。 

当字符串统一时，会出现微妙的边缘情况，例如 AAAAAA。 每个子串都充满了回文，所以所有子串都是好的。 相比之下，像 ABABAB 这样的交替字符串的行为非常不同，因为回文受到严格限制并且覆盖很快就会失败。 任何仅基于字母频率的天真的启发式在这里都会失败，因为 A 和 B 出现的频率相同，但结构才是重要的。 

另一个极端情况是非常短的子串。 单个字符子串永远不会是好的，因为它不包含长度大于 1 的回文。这会立即从考虑中消除所有长度为 1 的间隔。 

## 方法

 一种强力方法将检查每个子字符串 s[l:r]，并尝试验证每个字符是否位于该子字符串中包含的某个长度至少为 2 的回文数内。 即使使用巧妙的回文扩展检查，验证单个子串在最坏的情况下也是 O(n) 的。 这导致总体上的 O(n^3) 行为，在 n = 3·10^5 时完全无法使用。 

关键的观察结果是，条件“每个位置都属于长度> 1的回文”相当于说子串不能包含位置与任何对称配对隔离的“禁止结构”。 在 AB 字符串中，唯一有用的回文有两种形式：AA/BB（长度 2）和 ABA、BAB（长度 3）。 更大的回文是由这些局部模式组成的，因此覆盖范围减少到局部邻接约束。 

关键的简化是重新解释问题：我们不是检查每个子串内部的覆盖范围，而是根据其边界相互作用来表征哪些子串是有效的。 仅当子字符串包含“间隙”时，子字符串才算好，其中没有有效的回文可以覆盖某个区域，这有效地转换为可以使用前缀结构和字母之间的转换来跟踪的约束。 

这导致了该问题族的已知减少：对于每个位置，我们扫描并维护在保留覆盖范围的同时可以将以该位置结尾的有效子字符串扩展多远。 然后将每个索引的贡献计算为有效起始范围。

我们维护一个指针，用于跟踪以 i 结尾的有效子字符串可以开始的最早位置。 当我们扩展 i 时，我们根据局部回文模式是否仍然可以覆盖所有字符来更新此边界。 每次我们检测到结构违规（不能成为任何 AA/BB 或 ABA 模式一部分的位置）时，我们都会向前移动左边界。 

这将问题转化为线性扫描，其中每个右端点贡献有效左端点的连续间隔。

 ## 算法演练

 我们从左到右处理字符串，同时维护以当前位置结尾的子字符串的最小有效起始索引。 

1. 初始化一个指针`l = 0`，它表示子字符串 s[l:i] 可能仍然有效的最早索引。 

该指针只向前移动，从不向后移动，确保线性复杂度。 
2. 对于每个位置`i`，我们尝试扩展当前窗口 [l, i]。 在每一步中，我们都会检查新添加的字符是否仍然可以被窗口内长度至少为 2 的回文覆盖。 
3. 二进制字母表中唯一可能的回文覆盖是涉及邻接或一步对称的局部模式。 如果扩展创建的配置中最后几个字符无法形成或参与 AA、BB、ABA 或 BAB 模式，则窗口无效，我们必须移动`l`向前。 
4. 每当我们检测到当前窗口违反回文覆盖条件时，我们就会递增`l`直到窗口再次有效。 这确保了之前开始的所有子字符串`l`对于该端点无效。 
5. 一旦窗口有效，所有以`i`从 [l, i] 中的任意位置开始都很好。 我们添加`(i - l)`到答案。 
6. 对从 0 到 n−1 的所有 i 重复此过程。 

### 为什么它有效

 该算法保持不变式，即对于每个右端点 i，指针 l 是最小索引，使得 s[l:i] 中的每个字符仍然可以是完全在窗口内的至少一个有效本地回文的一部分。 由于有效性仅取决于局部邻接约束，因此任何违规都必须涉及边界附近的有限局部模式。 由于 l 仅在检测到违规时才向前移动，因此我们从不排除有效的开始，也从不包括无效的开始。 这可确保每个有效子字符串在其右端点精确计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    # We interpret A/B as 0/1 for simplicity
    a = [0 if c == 'A' else 1 for c in s]

    l = 0
    ans = 0

    for r in range(n):
        # We try to maintain a valid window [l, r]
        # A substring is invalid only if it introduces an unmatchable boundary.
        # For binary alphabet, violations only arise when we cannot form
        # local palindromic pairs covering the boundary region.

        while l < r:
            ok = True

            # check minimal local coverage condition:
            # last character must be able to pair or sit in ABA
            if r - l + 1 == 2:
                ok = (a[l] == a[r])
            elif r - l + 1 >= 3:
                # check if last char participates in some palindrome
                if a[r] == a[r-1] or a[r] == a[r-2]:
                    ok = True
                else:
                    ok = False

            if ok:
                break
            l += 1

        if r > l:
            ans += (r - l)

    print(ans)

if __name__ == "__main__":
    solve()
```该代码维护一个滑动窗口。 循环内的检查是局部可行性测试，确保最新的字符仍然可以属于长度至少为 2 的回文。如果不是，我们从左侧收缩，直到再次成为可能。 

关键的细节是，只有最后两个或三个字符才能确定当前扩展是否可以参与有效的回文，因为任何覆盖新字符的回文都必须将其包含在二进制字母表中长度为 2 或 3 的对称结构中。 

贡献`(r - l)`计算以以下结尾的子字符串的所有有效起始位置`r`。

 ## 边缘情况

 单个字符串暴露了这样一个事实：根本不存在长度大于 1 的回文，迫使答案立即为零。 该算法会处理这个问题，因为窗口永远不会对长度为一有效。 

像 AAAAA 这样的完全一致的字符串显示了相反的极端，其中长度至少为 2 的每个子字符串内部都富含回文。 滑动窗口永远不需要缩小，因此贡献可以最大限度地累积。 

诸如 ABABAB 之类的交替字符串表现出最严格的行为。 左指针很早就稳定下来，并且只有短子串有效，这表明局部邻接约束如何主导全局结构。
