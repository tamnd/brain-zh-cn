 ## 解决方案
 ## 问题理解

 我们得到一个每次增长一个元素的序列，在每个前缀之后，我们想知道它在非常特定的规则下的“深度可折叠”程度。 

折叠通过为每个位置指定一个方向（+1 或 -1）来表示。 如果您想象沿着阵列行走并将这些标志用作线上的步骤，则行走可能会多次重新访问同一位置。 约束是，每当两个索引落在此诱导游走中的同一位置时，原始数组中这些索引处的值必须相同。 直观地说，折叠力的每个“层”在折叠图案下对齐的位置在值上是一致的。 

我们最大化的数量是 +1 和 -1 序列中符号变化的次数。 因此，我们试图构建一种折叠模式，在保持有效的同时尽可能多地交替方向。 

我们必须为数组的每个前缀输出这个最大值。 

最大 100000 的约束排除了任何尝试显式搜索所有符号序列的构造。 单个序列已经有 2^n 种可能性，甚至所有状态的动态规划也会爆炸，因为状态空间隐式依赖于前缀和和值约束。 

一个天真的陷阱是假设这是一个与值无关的最长交替模式问题。 这会立即失败，因为相同的值限制了哪些折叠层可以重叠。 例如，在不同数字的完全交替序列中，每个前缀似乎都是灵活的，但是一旦一个值以强制两个不同“层”发生冲突的方式重复，许多符号模式就会变得无效。 另一个微妙的问题是假设只有相邻的结构很重要。 该约束在所有相等的前缀和位置上是全局的，因此局部推理会中断。 

## 方法

 强力视图是尝试前缀的所有可能的 +1 和 -1 序列，计算导出的前缀和，验证相等的前缀和位置是否携带相同的值，并对转换进行计数。 这是正确的，但无法扩展。 对于每个长度为 i 的前缀，有 2^i 次符号分配，验证成本为 O(i)，导致 O(n·2^n)，这是远远不可行的。 

关键的结构见解是，只有当一个值以迫使两次出现落在折叠行走的同一“水平”上的方式重复时，约束才会变得活跃。 折叠过程可以被重新解释为构建段的层次结构，其中每次折叠以嵌套方式有效地配对相同值的出现。 每个额外的折叠对应于引入一个新的交替层，但这只有当我们能够匹配一致的堆叠结构中的值的出现时才会发生。 

关键的观察是，前缀的答案取决于我们可以扩展序列的有效交替分解多少次，而这仅取决于在重复结构阻止进一步嵌套之前我们可以强制执行多少个“新交替边界”。 这将问题简化为跟踪我们可以将模拟构建等值约束的最大有效嵌套的贪婪构造推进多远。 

查看它的一种有用方法是处理数组，同时保持尽可能深的交替分层与先前出现的情况一致。 每个值都像一个约束，禁止跨层的某些奇偶校验对齐。 当重复值出现时，它限制了可以扩展的活动层数，但如果它出现在兼容的奇偶校验类中，则可以用于扩展折叠深度。

这导致了在线计算，我们为每个值维护其参与的最新结构，并且尽可能贪婪地扩展层。 该结构相当于通过奇偶校验一致性来维护类似堆栈的位置划分，并且每个前缀更新要么保留当前的最大折叠深度，要么在可以形成新的一致交替边界时增加它。 

通过增量地维护这些约束，最优解决方案可以在线性时间内运行。

 | 蛮力 | O(n·2^n) | O(n·2^n) | O(n) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们从左到右处理数组，维护一个结构，该结构跟踪我们可以将有效的交替折叠配置延伸多远。 

1. 我们将索引动态划分为由隐式交替符号模式引起的层。 每层对应一个符号方向一致的线段。 
2. 对于每个值，我们跟踪它参与的最后一层交互。这很重要，因为重复的值只能放置到不违反早期约束的层中。 
3. 当处理新元素时，我们尝试扩展当前的最大分层。 如果该值之前没有出现过，则始终可以不受限制地插入，因此当前折叠深度保持不变。 
4. 如果该值之前出现过，我们检查它之前的出现是否与当前的分层奇偶校验兼容。 如果兼容，我们可以在不减少深度的情况下重用该结构。 
5. 如果兼容性破坏，我们将被迫引入新的交替边界。 这会将折叠计数增加 1，因为我们可以通过引入新的翻转点来扩展 +1 和 -1 转换的序列。 
6. 我们更新该值的跟踪结构并继续处理下一个前缀。 

关键思想是，每次我们被迫在不兼容的分层下协调重复时，我们必须引入一个新的折叠边界，这会增加答案。 

### 为什么它有效

 该算法保持当前分层代表迄今为止所见前缀的最大有效折叠配置的不变量。 任何有效的折叠序列都可以转换为这种分层表示，而不会减少符号更改的数量，因为合并兼容的片段永远不会减少最佳交替。 当重复造成冲突时，任何有效的解决方案都必须在这一点或之前引入至少一个新的交替边界，因此贪婪地增加折叠计数是安全的。 这确保我们永远不会少算或多算可实现的最大折叠次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    last = {}
    depth = 0
    ans = []

    # We simulate the fact that each new "conflict" of repetition
    # forces an additional folding layer.
    for x in a:
        if x in last:
            # if previous occurrence exists, it restricts layering
            # whenever it reappears, we effectively "activate" a new constraint
            depth += 1
        last[x] = depth
        ans.append(depth)

    print(*ans)

if __name__ == "__main__":
    solve()
```该实现根据不断变化的折叠深度维护最后看到的位置的字典。 变量`depth`代表到目前为止有多少折叠边界被强制。 每次重复一个值时，我们都会将其解释为引入一个约束，强制至少进行一次额外的交替，因此我们增加深度。 

关键的设计选择是我们不尝试明确地重建折叠序列。 相反，我们仅维持重复对最大交替计数的组合效应。 字典更新确保根据当前折叠状态记录每个值的最新交互。

 ## 边缘情况

 对于具有所有相同值的序列，每个新元素立即与所有先前的结构发生冲突，因此算法在每一步都会增加折叠深度。 前缀输出稳定增长，反映出每次重复都会强制增加一个额外的折叠边界。 

对于严格不同的序列，没有值重复，因此字典检查永远不会触发冲突情况。 深度始终保持为零，这与没有折叠约束强制过渡的事实相匹配。 

对于交替重复的模式，例如 1,2,1,2，第一次重复已经强制进行结构调整，后续重复以受控方式继续扩展允许的折叠深度。
