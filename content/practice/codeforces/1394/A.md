 ## 解决方案
 ## 问题理解

 我们得到了一系列“有趣的值”，代表杜每天的信息有多有趣。 在流程开始之前，我们可以按任意顺序重新排列这些值。 确定订单后，日子从左到右进行。 

每天，如果 Du 当前未静音，我们会从序列中获取下一个值并将其添加到总乐趣中。 如果该值大于给定阈值`m`，博博尼乌生气了，强迫杜停止说话。`d`天。 在安静的日子里，不会消耗任何价值，也不会获得乐趣，整个过程只是在时间上向前跳跃。 

目标是对数组进行排列，以使累积的总乐趣最大化。 

关键的困难在于，大的值是危险的，因为它们会触发强制沉默，从而浪费即将到来的头寸。 小值是安全的，因为它们永远不会触发惩罚，并且总是有效地填补活跃的演讲时间。 

约束条件达到`n = 100000`，这会立即排除任何阶乘或二次排列搜索。 甚至`O(n^2)`对所有重新排序进行贪心模拟是不可能的。 我们需要一种策略，其中每个元素在受控结构中只放置一次，最好是在`O(n log n)`或者`O(n)`时间。 

一个天真贪婪的降序排序并总是选择最大的可用值可能会失败，因为过早放置一个大值可能会由于长时间的静音间隔而浪费太多的未来位置。 相反，如果用大值来“阻止”时间，否则小值会被浪费，那么总是推迟大值也可能不是最佳选择。 

当所有值都大于时，会出现微妙的边缘情况`m`。 然后，每个选定的元素都会触发静音。 例如，`n = 5, d = 2, m = 0, a = [1,2,3,4,5]`。 任何排序仍然会导致频繁的阻塞，并且该策略必须确保我们只使用大值的最佳位置，从而最大限度地减少浪费的放置。 

当出现另一种边缘情况时`d = 1`。 然后，每个大值仅在第二天阻塞，因此间距很小，问题变得更接近于简单选择最佳位置。 任何过于复杂的调度都是不必要的，但仍然必须产生正确的结果。 

## 方法

 暴力方法将枚举数组的所有排列，模拟每个排列的过程，并计算所得的乐趣。 对于每个排列，我们从左到右扫描，维护一个指针和一个冷却计数器。 每当我们遇到大于的值`m`，我们跳过下一个`d`职位。 这个模拟成本`O(n)`每个排列，并且有`n!`排列，导致不可行`O(n! * n)`复杂。 

主要的结构观察是只有大于的值`m`影响阻塞的动态。 价值观`<= m`是“安全的”：它们永远不会触发静音，因此总是独立于订购而做出贡献，除了有多少活跃天数可以放置它们。 问题归结为决定在可用发言时段的时间线中将大值放置在何处。 

我们可以将数组分为两组：安全值（`<= m`）和危险值（`> m`）。 每当我们有可用的演讲日时，都应始终贪婪地采用安全值，因为它们永远不会减少未来的可用性。 挑战在于如何放置危险值，以便最大限度地减少它们的阻塞效应，同时仍然收集它们的贡献。 

一个关键的见解是按降序处理危险值，并使用贪婪调度结构模拟将它们放入时间线中。 每个危险值都会消耗一个活跃日并阻止下一个活跃日`d`天，有效地在时间线上创造了“间隙”。 同时，安全值只是填充所有剩余的未锁定位置。 

这导致了一个贪婪的过程，我们维护剩余的活动插槽数量以及可用于填补空白的安全值。 我们总是优先考虑将较大的危险值放在第一位，因为它们会产生相同的阻塞成本，但会产生更高的奖励。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!·n) | O(n!·n) | O(n) | 太慢了|
 | 分割+贪婪调度| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将数组转换为两个排序组，并模拟可用天数中危险值的最佳调度。 

1. 将数组拆分为两个列表：一个包含大于的所有值`m`以及包含小于或等于的所有值的一个`m`。 这种分离是必要的，因为只有较大的群体才会触发阻塞行为。 
2. 按降序对两个列表进行排序。 最大值必须放在可用时隙中较早的位置，因为它们以相同的阻塞成本提供更高的即时增益。 
3. 计算我们可以使用多少个“有效位置”。 每个危险值占用一天并删除下一天`d`距离可用天数，因此每个展示位置都会消耗一个大小的块`d + 1`。 
4. 按降序贪婪地迭代危险值，只要我们在有效槽位方面仍然有可用容量，就放置每个危险值。 每个位置都会为答案贡献其价值并减少剩余容量。 
5. 输入所有可能的危险值后，用安全值填充所有剩余的可用天数。 由于安全值永远不会触发阻塞，因此我们只需采用尽可能多的值并将它们全部添加到答案中。 
6. 如果安全值多于剩余槽位，我们仍然将它们全部取走，因为安全值不会相互干扰或与调度发生干扰。 

### 为什么它有效

 关键的不变量是每个危险值恰好消耗一个“激活槽”并确定性地删除`d`未来可用的插槽，无论放置在何处。 这使得所有危险值在成本方面都可以互换，仅在收益方面有所不同。 因此，按降序对它们进行排序并贪婪地选择可以在固定数量的可能激活下最大化总增益。 安全值不会影响未来激活的可用性，因此一旦危险调度得到修复，它们始终可以独立添加。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, d, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    big = []
    small = []
    
    for x in a:
        if x > m:
            big.append(x)
        else:
            small.append(x)
    
    big.sort(reverse=True)
    small.sort(reverse=True)
    
    # maximum number of big elements we can place
    # each big consumes (d + 1) effective positions
    max_big = (n + d) // (d + 1)
    
    take_big = min(len(big), max_big)
    
    ans = sum(big[:take_big])
    
    # remaining positions after placing big elements
    remaining_slots = n - take_big * (d + 1)
    
    # we can place all small elements in remaining slots
    ans += sum(small[:remaining_slots])
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先根据值是否超过将值分为危险组和安全组。`m`。 按降序对两组进行排序可确保我们始终首先考虑最有价值的元素。 

表达式`(n + d) // (d + 1)`计算在最佳情况下我们可以触发“阻止事件”的次数，因为每个危险值占用一天并禁用下一天`d`天。 这给出了可以调度的大元素数量的上限。 

选择要采用的大元素后，我们计算小元素剩余可用的实际天数。 这些只是填充了最佳可用的安全值。 

关键的微妙之处在于我们从不明确模拟日常的转变。 相反，我们将过程压缩为计算每个大值消耗了多少个有效槽。

最终答案是 38。这显示了大值对容量消耗的主导程度。

 ## 边缘情况

 当所有值都小于或等于`m`，该算法将所有内容放入小组中，并计算剩余的槽位：`n`。 不会发生阻塞，因此答案成为所有值的总和。 例如，`n = 4, m = 10, a = [1,2,3,4]`结果选择所有四个元素。 

当所有值都超过`m`，算法完全依赖于容量公式`(n + d) // (d + 1)`。 每个选定的元素都会消耗一个完整的块，并且只选择最大的几个。 为了`n = 5, d = 2, a = [5,4,3,2,1]`，最多选择两个元素，给出`5 + 4 = 9`。 

什么时候`d`相对于`n`，只能使用一两个大元素。 剩余的槽位完全由小值（如果存在）填充。 该案例证实，无论订购如何，容量计算都能正确限制危险值的影响。
