 ## 解决方案
 ## 问题理解

 我们有一个网格代表一个迷宫般的世界。 有些单元格是墙壁，有些是空地板，有些是标记为起始机器人位置的特殊生成位置，还有一个单元格是目标。 任务是让至少一个机器人到达目标单元。 

关键机制是机器人可以发出单个运动命令。 当机器人被告知移动到相邻的单元格时，结果取决于那里有什么。 如果目标单元是空的，机器人只会移动，然后立即自毁，这意味着它在执行命令后消失。 如果目标单元格包含另一个机器人，移动机器人会将其向前推入下一个单元格，在这种情况下，被推入的机器人将存活下来并有效地成为新的活动机器人。 如果由于墙壁或推动受阻而导致移动无效，则移动会失败，但移动机器人仍然会自毁。 

重要的后果是，机器人通常是一次性资源，除非它能够通过推动另一个机器人前进来“自我转移”。 这使得长路径变得昂贵，除非我们可以重复使用网格上已经存在的机器人，或者我们可以在特殊的生成单元中生成新的机器人。 

输入描述了一个包含最多 1000 x 1000 个单元的网格，因此最多有 100 万个节点。 每个状态的二次或重复洪水填充会太慢，因此任何解决方案都必须大致呈线性或在网格上具有较小的常数因子。 这立即表明了最短路径风格的技术，如 BFS 或 0-1 BFS。 

当将所有移动视为统一成本时，会出现微妙的失败情况。 考虑一条路径，每次进入空的单元格都会消耗一个新的机器人，但进入已经被机器人占据的单元格会有效地“回收”现有的机器人，并且不需要额外的召唤。 如果我们忽略这种区别，我们就会高估或低估所需的机器人数量。 

例如，如果从生成点到目标的路径仅穿过空单元格，则忽略机器人力学的天真的最短路径会将其视为单个路径。 实际上，每个空步骤都会消耗唯一的活动机器人，这意味着我们需要重新召唤，除非我们在路径上遇到另一个机器人。 

另一种边缘情况是，目标与生成点相邻，但被墙隔开，除非经过很长的绕道。 天真的贪婪方法可能会错误地认为直接邻接就足够了，而不考虑推送约束。 

## 方法

 暴力模拟将尝试对每个可能的机器人动作序列进行建模。 从由网格配置和主动机器人位置组成的状态，我们将在所有四个方向上分支并模拟运动，包括推动和自毁。 状态的数量呈指数增长，因为每次移动要么消耗一个机器人，要么通过移动机器人来修改网格。 即使进行剪枝，状态空间基本上也是网格上机器人的所有可达配置，这远远超出了 1000 x 1000 板的任何可行限制。 

关键的观察是我们实际上并不关心完整的配置。 我们只关心将“可用机器人链”从任何生成位置传播到目标的最便宜的方法。 包含机器人的网格单元的行为就像免费的中继点：如果我们到达一个，我们可以继续移动而无需花费新的召唤。 相比之下，空单元格消耗一单位资源。

这将问题转化为网格上的最短路径问题，其中边缘具有两种不同的成本。 移动到一个空的牢房需要花费一个，因为它会消耗一个机器人并且需要一个新的召唤才能继续。 移动到已经包含机器人（或生成点）的单元格中的成本为零，因为我们可以通过推动或启动那里来转移控制权，而无需消耗额外的资源。 目标细胞被视为正常目标。 

这种结构正是 0-1 BFS 的设计目的。 每个单元格都是一个节点，每次移动的成本为 0 或成本 1，具体取决于目标类型。 我们从所有生成位置开始运行多源 BFS，初始成本为 1，因为从生成位置开始会消耗一个机器人。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 全面模拟机器人动作 | 指数| 指数| 太慢了 |
 | 具有均匀 BFS 的网格最短路径 | O(nm) 但成本模型不正确 | O(纳米) | 错误答案 |
 | 网格状态上的 0-1 BFS | O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 1. 初始化一个距离网格，其中每个单元格存储到达该网格所需的最小机器人召唤数量。 将所有值设置为无穷大。 
2. 将所有生成单元推入初始距离为 1 的双端队列中。这反映了在生成时激活机器人需要花费一次召唤。 
3. 当双端队列不为空时，从前面弹出一个单元格并考虑它的四个邻居。 
4. 如果邻居是墙，则完全跳过它，因为运动无法穿过它。 
5. 如果邻居是一个空单元格，则移动到其中的成本+1。 如果我们找到更好的值，则更新其距离并将其推到双端队列的后面。 后推保留了 BFS 排序，以实现更高成本的转换。 
6. 如果邻居是生成单元或已经包含机器人，则移动到其中的成本为+0。 如果有改进则更新其距离并将其推到双端队列的前面。 这反映出我们可以继续进行，而无需花费额外的召唤。 
7. 继续，直到处理完所有可达状态。 
8. 答案是在球门单元处记录的最小距离。 如果仍然无穷大，则输出-1。 

双端队列排序很重要的原因是，我们总是希望在那些消耗额外机器人的状态之前扩展不消耗额外机器人的状态。 这保证了当我们第一次完成一个单元格时，我们已经使用了尽可能少的召唤次数来到达它。 

### 为什么它有效

 每个单元格代表使用一定数量的召唤将活动机器人放置在该位置的最著名方法。 这些转换保留了最优性，因为每次移动要么保留当前的召唤数量（当使用现有的机器人中继时），要么将其增加一个（当进入空旷的空间并消耗活动机器人时）。 由于所有成本都是 0 或 1，所以第一次按成本递增顺序处理状态时，我们已经考虑了达到该状态的所有更便宜的方法，因此我们绝不会错过更好的机器人链分解。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

INF = 10**18

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    dist = [[INF] * m for _ in range(n)]
    dq = deque()

    # multi-source initialization
    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'A':
                dist[i][j] = 1
                dq.append((i, j))

    directions = [(1,0), (-1,0), (0,1), (0,-1)]

    while dq:
        x, y = dq.popleft()

        for dx, dy in directions:
            nx, ny = x + dx, y + dy
            if nx < 0 or nx >= n or ny < 0 or ny >= m:
                continue
            if grid[nx][ny] == '#':
                continue

            # cost depends on cell type
            cost = 0 if grid[nx][ny] != '.' else 1
            nd = dist[x][y] + cost

            if nd < dist[nx][ny]:
                dist[nx][ny] = nd
                if cost == 0:
                    dq.appendleft((nx, ny))
                else:
                    dq.append((nx, ny))

    # find B
    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'B':
                ans = dist[i][j]
                print(-1 if ans == INF else ans)
                return

t = int(input())
for _ in range(t):
    solve()
```该解决方案在网格上建立一个距离场，其中每次移动都被分类为通过现有机器人的零成本中继或新召唤的机器人的一次性消耗。 双端队列确保始终首先处理零成本扩展。 

一个常见的错误是平等地对待所有可遍历的单元格，这错误地将问题简化为标准 BFS。 空单元和包含机器人的单元之间的区别是整个困难的根源。 

另一个微妙的点是初始化：所有生成点都以成本 1 开始，而不是零，因为我们正在计算必须召唤多少个机器人，并且使用生成点已经消耗了该预算的一个单位。 

## 工作示例

 考虑一个小网格，其中生成点与目标之间由一个空单元格分隔开：```
A . B
```唯一的路径需要从 A 进入空单元格，然后进入 B。 

| 步骤| 队列状态 | 细胞| 成本| 行动|
 | ---| ---| ---| ---| ---|
 | 1 | (一)| 一个 | 1 | 开始 |
 | 2 | (.)| 。 | 2 | 搬入空|
 | 3 | （二）| 乙| 2 | 迈向目标|

 答案是 2，因为我们在 A 处消耗了一个机器人，并消耗了另一个机器人来穿过空单元格。 

现在考虑一个机器人作为中继存在的网格：```
A R B
```这里R被视为机器人中继点。 

| 步骤| 队列状态 | 细胞| 成本| 行动|
 | ---| ---| ---| ---| ---|
 | 1 | (一)| 一个 | 1 | 开始 |
 | 2 | （右）| 右 | 1 | 零成本搬迁|
 | 3 | （二）| 乙| 1 | 零成本搬迁|

 答案变成1，因为现有的机器人允许连续转移而无需额外召唤。 

这两个案例显示了消耗空闲空间和使用现有机器人作为免费连接器之间的核心区别。

 ## 边缘情况

 当球门完全被墙壁包围时，除了一条狭窄的空牢房走廊外，就会出现一种极端情况。 该算法正确地累积每个空步骤的成本，从而强制进行多次召唤。 

另一种情况是存在多个生成点，但只有一个生成点通向有效的中继链。 由于该算法是多源的，因此所有生成都以相同的初始成本开始，并且最短的传播自然会选择最佳的起点。 

最后一个微妙的情况是，当生成点与目标相邻时，但唯一有效的转换需要推动另一个机器人。 在这种情况下，当且仅当推链存在于网格结构中时，通过中继的零成本转换确保路径仍然被发现，因为 BFS 只允许通过有效的机器人单元进行零成本移动。
