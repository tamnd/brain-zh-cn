 ## 解决方案
 ## 问题理解

 我们有一张桌子`m`行和`n`列。 每一行属于一个机器人参与者，并且每一行都有自己的布尔程序。 在每一列中，值都是以下排列`0, 1, ..., m - 1`，因此每个值在该列中只出现一次。 

对于每一列`j`，我们选择一个阈值`z[j]`之间`0`和`m`。 行的输入`i`该列中的值变为布尔值`x[i][j] < z[j]`。 

然后该行评估这些`n`通过其给定序列的布尔输入`and`和`or`指示。 这些程序是单调的，并且具有特殊的非重复属性：每个中间值都用作至多一条后续指令的输入。 每行的最终值是该行的程序的结果。 任务是选择阈值，以便准确地`s`的`m`最终结果是`1`。 该声明保证此类阈值始终存在。 

约束条件`n * m <= 3 * 10^5`是关键数值界限。 我们买不起任何接近的东西`O(nm * n)`或者`O(nm * m)`在最坏的情况下。 我们需要一种与总输入大小基本呈线性关系的算法。 个人的界限`n`和`m`每个都能达到`3 * 10^5`，但他们的产品仍然很小，所以正确的复杂性目标是`O(nm)`。 

有几种边缘情况可能会悄无声息地破坏实现。 

什么时候`s = 0`，每个程序都必须保持为零。 正确的答案就是所有阈值都为零。 例如，```
1 3 0
0
1
2
```有正确的输出```
0
```在检查目标之前执行一个阈值增加的粗心实现可能已经使一个程序等于`1`。 

案例`s = m`是相反的边界。 每个程序都必须成为一个程序。 例如，```
1 3 3
0
1
2
```有正确的输出```
3
```因为`0 < 3`,`1 < 3`， 和`2 < 3`。 忘记阈值允许等于`m`将使此案变得不可能。 

案例`n = 1`根本没有布尔指令。 每个程序仅包含其单个输入。 由于每一列都是一个排列，因此选择`z[1] = s`精确生成具有值的行`0, 1, ..., s - 1`等于一。 例如，```
1 4 2
0
1
2
3
```解决的是`2`。 

一个更微妙的情况是`and`其第一个输入变为 1 而第二个输入仍为零的门。 门必须保持为零，因此传播必须立即停止。 例如，对于```
2 3 1
1 2 1
1 2 1
1 2 1
0 0
1 1
2 2
```每个程序计算`input1 and input2`。 仅提高第一个阈值无法激活程序。 传播每个输入更改而不检查其他输入的实现会错误地增加答案计数。 

相反的情况发生在`or`：如果门的输出先前为零，则将一个输入从零更改为一会立即激活门。 传播逻辑必须区分这两个操作。 

## 方法

 最直接的解决办法就是一一提高门槛。 最初每个阈值都为零，因此每次比较`x[i][j] < z[j]`是假的。 我们可以将某个阈值增加一，重新计算所有受影响的布尔程序，并继续直到恰好`s`程序返回一。 

这是正确的，因为每个阈值只会增加，因此每个输入只能更改一次，从零到一。 单调性`and`和`or`意味着程序输出也只能从零移动到一。 由于所有阈值最终都会达到`m`，每个输入最终都会变成一个，每个程序最终都会返回一个。 因此，一路上必须遇到所需的计数。 这些观察也是官方解决方案的基础。 

直接实现的问题是重新计算量。 有`nm`阈值增量。 如果每个增量都使我们评估整个程序`O(n)`说明，最坏的情况是`O(n^2m)`，太大了。 和`n * m = 3 * 10^5`，甚至一个额外的因素`n`是不可接受的。 

我们可以通过观察一个阈值增量恰好改变一行的一个输入来改进这一点。 每列的排列属性免费提供了这一点。 如果`z[j]`变化自`t`到`t + 1`，列中唯一新的真实比较`j`是包含该值的行`t`。 

蛮力解决方案之所以有效，是因为它在进行一位更改后会重复评估整个程序。 但几乎所有这些工作都是不必要的。 只有依赖于改变的值的指令才可能改变。 

非重复条件给出了关键的最终简化。 指令产生的每个值都用作后续指令的输入，最终结果除外。 因此，在输入从 0 变为 1 后，只有一条可能的路径可以传播该变化。 在整个算法过程中，每条指令本身最多可以从零变为一一次。 因此，在所有`m`程序，至多`O(nm)`指令值不断变化。 

我们可以用`parent`大批。 对于指令的每个输入值，`parent[value]`告诉我们哪个指令消耗它。 当一个值变成 1 时，我们检查它的父级。 如果该父级保持为零，则传播停止。 如果它的输出变成 1，我们就从该输出继续。 由于每个中间值只有一个父值，因此不需要图遍历或重复重新计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(n²m)`|`O(nm)`| 太慢了 |
 | 仅重新计算受影响的程序 |`O(n²m)`|`O(nm)`| 总体来说太慢了 |
 | 每列二分搜索 |`O(nm log(nm))`|`O(nm)`| 可能被接受，但没有必要 |
 | 增量传播 |`O(nm)`|`O(nm)`| 已接受 |

 ## 算法演练

 1. 从每个阈值都为零开始。 每个表值都是非负的，因此每次比较`x[i][j] < 0`是假的。 因此，每个程序都以零值开始。 
2. 保存每个输入和每个中间指令的当前布尔值。 最初所有这些值都为零。 
3. 对于每个输入值，存储其唯一的父指令。 输入限制保证没有值被使用两次，因此该父级是唯一的。 
4. 一次处理一列。 对于固定柱`j`，将其阈值从零增加到`m`。 当阈值从`t`到`t + 1`，找到该列中值为的唯一行`t`。 
5. 更改该行对应列的输入`j`从零到一。 在此操作期间没有其他行或列发生更改，因为该列是以下的排列`0, ..., m - 1`。 
6. 遵循更改值的父级。 如果没有父级，则该值本身就是最终输出。 这仅在以下情况下直接发生：`n = 1`。 
7. 否则使用其两个输入来评估父指令。 如果它是一个`and`，仅当两个输入均为 1 时，其输出才变为 1。 如果它是一个`or`，只要至少一个输入为 1，其输出就变为 1。 
8. 如果指令的输出保持为零，则停止传播。 未来其他地方的阈值变化可能会影响它，但当前的变化不能传播得更远。 
9. 如果指令的输出从零变为一，则将其标记为 1，并从该输出继续通过其父指令。 一条指令永远不需要从零变为一两次。 
10. 每当一行的最终值从零变为一时，增加成功程序的全局计数。 如果这个计数变成`s`，立即输出当前阈值。 
11.如果`s = 0`，立即输出全零阈值。 如果`n = 1`，问题没有说明，答案很简单`z[1] = s`。 

### 为什么它有效

 不变的是，在每次处理阈值增量之后，每个存储的`val`正是每个程序的相应部分针对当前阈值产生的值。 

最初，不变量成立，因为所有输入和所有指令输出均为零。 在增量过程中，只有一个输入从零变为一。 从该输入无法访问的每条指令均不受影响。 对于更改值的唯一父级，我们完全根据其操作重新计算其输出。 如果其输出发生变化，则相同的参数适用于其唯一的父级。 因此，每个可能受影响的值都会更新，而每个不受影响的值仍然正确。 

因为`and`和`or`是单调的，没有任何值可以从一变回零。 因为程序是不重复的，所以每个中间值最多有一个父代，因此每个值最多可以传播一次。 当最终输出发生变化时，恰好有一个程序从零变为一。 因此，维护的计数始终是返回 1 的程序的真实数量。 

在阈值全部等于 0 时，计数为零，而在阈值全部等于 0 时，计数为零`m`每个输入都是一个，每个程序都返回一个。 由于每个单独的更新最多可以将计数增加 1，因此每个目标计数从零到`m`遇到。 当计数达到时，算法恰好停止`s`。 

## Python 解决方案```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    n, m, target = map(int, input().split())

    # n == 1 means every program consists of its only input.
    # Since each column is a permutation of 0..m-1, z[0] = target
    # makes exactly target rows true.
    if n == 1:
        for _ in range(m):
            input()
        print(target)
        return

    inst_count = n - 1
    width = 2 * n - 1
    total_values = m * width
    total_instructions = m * inst_count
    total_cells = n * m

    # For instruction k of row r:
    # left[r * inst_count + k]
    # right[r * inst_count + k]
    # op[r * inst_count + k]
    left = array('i')
    right = array('i')
    op = array('b')

    # parent[base + value - 1] is the local value number
    # of the instruction consuming that value.
    parent = array('i', [0]) * total_values

    for row in range(m):
        base = row * width
        ibase = row * inst_count

        for p in range(1, n):
            a, b, operation = map(int, input().split())

            idx = ibase + p - 1
            left.append(a)
            right.append(b)
            op.append(operation)

            out = n + p
            parent[base + a - 1] = out
            parent[base + b - 1] = out

    # events[col * m + value] = row containing that value in this column.
    # When z[col] grows from value to value + 1, this row's input changes.
    events = array('i', [0]) * total_cells

    for row in range(m):
        values = list(map(int, input().split()))
        for col, value in enumerate(values):
            events[col * m + value] = row

    if target == 0:
        print(*([0] * n))
        return

    thresholds = [0] * n

    # Current values of all inputs and intermediate results.
    vals = bytearray(total_values)

    active = 0

    for col in range(n):
        event_base = col * m
        local_input = col + 1

        for value in range(m):
            row = events[event_base + value]
            thresholds[col] = value + 1

            base = row * width
            current = local_input

            while True:
                # For n > 1, every input has a parent.
                out = parent[base + current - 1]

                if out == 0:
                    break

                out_pos = base + out - 1

                # This instruction has already become one.
                if vals[out_pos]:
                    break

                instruction = out - n
                idx = row * inst_count + instruction - 1

                a = left[idx]
                b = right[idx]

                if op[idx] == 1:
                    new_value = vals[base + a - 1] & vals[base + b - 1]
                else:
                    new_value = vals[base + a - 1] | vals[base + b - 1]

                if not new_value:
                    break

                vals[out_pos] = 1

                if out == width:
                    active += 1
                    break

                current = out

            if active == target:
                print(*thresholds)
                return

    # The statement guarantees that a solution exists.
    print(*thresholds)

if __name__ == "__main__":
    solve()
```第一个特殊案例手柄`n = 1`。 这样的程序中没有指令，因此最终结果只是唯一的比较。 由于该列包含从零到的每个值`m - 1`， 临界点`s`准确激活`s`行。 

为了`n > 1`,`width = 2n - 1`是一个程序中的值的数量。 数组`left`,`right`， 和`op`连续存储每一行​​的所有指令。 使用平面数组可以避免在以下情况之一时创建数十万个小型 Python 列表：`n`或者`m`很大。 

这`parent`数组由行和本地值编号索引。 读取指令时，其两个操作数都接收该指令的输出作为其父操作数。 非重复条件保证这些分配永远不会发生冲突。 最终输出没有父项，因此其父项保持为零。 

这`events`数组存储每列的逆排列。 而不是保留整个表并重复搜索列中的值`t`，我们直接检索包含的行`t`在`O(1)`。 其平坦指数为`col * m + value`。 

传播循环是解决方案的核心。`current`是刚刚变为 1 的本地值。 它的父指令是从获得的`parent`。 如果输出已经是 1，则无需再传播。 否则，根据指令的两个当前输入来评估指令。 

操作编码如下：`1`方法`and`和`2`方法`or`。 由于所有值仅从零移动到一，因此一条指令在整个执行过程中只能进行一次这样的转换。 

最终输出有本地索引`2n - 1`，这正是`width`。 当这个值变为1时，对应的程序刚刚成功，所以`active`是递增的。 

Python 中不存在整数溢出问题。 在实施过程中，`array('i')`用于索引和操作数的紧凑存储，而`bytearray`每个布尔值使用一个字节存储。 

阈值已指定`value + 1`在传播之前，因为比较是严格的。 表值等于`value`当阈值达到时准确地变为真`value + 1`。 忘记这种严格的不平等是阈值扫描中最有可能出现的误差。 

## 工作示例

 官方样本有`n = 4`,`m = 3`，目标是`2`。 它的表是```
0 1 2 2
2 2 1 0
1 0 0 1
```而这三个方案正是声明中给出的方案。 官方输出使用阈值`0 1 2 3`，这使得第二行和第三行返回 1。 

对于增量算法，我们可以先处理完第一列，然后继续处理第二列。 

| 专栏 | 新门槛| 输入更改的行 | 节目数 |
 | --- | --- | --- | --- |
 | 1 | 1 | 第 1 行 | 0 |
 | 1 | 2 | 第 2 行 | 0 |
 | 1 | 3 | 第 3 行 | 0 |
 | 2 | 1 | 第 3 行 | 0 |
 | 2 | 2 | 第 1 行 | 0 |
 | 2 | 3 | 第 2 行 | 1 |
 | 3 | 1 | 第 3 行 | 1 |
 | 3 | 2 | 第 1 行 | 1 |
 | 3 | 3 | 第 2 行 | 2 |

 最后一行计数达到目标`2`，因此算法以有效阈值向量停止。 确切的向量可能与官方样本不同，因为任何有效的答案都会被接受。 

第二个例子故意更小并且仅使用`and`运营：```
2 3 1
1 2 1
1 2 1
1 2 1
0 0
1 1
2 2
```每行计算`input1 and input2`。 

| 专栏 | 门槛| 更改行 | 更改输入 | 节目数 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 |`input1: 0 -> 1`| 0 |
 | 1 | 2 | 2 |`input1: 0 -> 1`| 0 |
 | 1 | 3 | 3 |`input1: 0 -> 1`| 0 |
 | 2 | 1 | 1 |`input2: 0 -> 1`| 1 |

 第一行的`and`仅当第二个输入发生变化后，指令才变为一条指令。 第二个输入的传播立即到达最终输出，因此算法返回阈值`3 1`。 

这个例子说明了为什么算法不能盲目传播。 更改的输入并不意味着其父级发生更改。 对于一个`and`，另一个输入必须已经是一个。

            pos += 1
            prog.append((a, b, operation))
        programs.append(prog)

    table = []
    for _ in range(m):
        table.append(list(map(int, first[pos].split())))
        pos += 1

    count = 0

    for row in range(m):
        vals = [False] * (2 * n)

        for j in range(n):
            vals[j + 1] = table[row][j] < out[j]

        for p, (a, b, operation) in enumerate(programs[row], start=1):
            if operation == 1:
                vals[n + p] = vals[a] and vals[b]
            else:
                vals[n + p] = vals[a] or vals[b]

        if vals[2 * n - 1]:
            count += 1

    assert count == s
    return out

 “一切平等的价值观”一词在这里需要一个限定条件。 整个列不能包含相等的值，因为该语句要求每列都是以下的排列`0, ..., m - 1`。 最接近的有效压力情况是一个表，其中每行在列之间具有相同的模式，例如 row`i`含有`i`在每一列中。 上面的 AND 和 OR 测试正是使用该结构。 

## 边缘情况

 对于`s = 0`，算法在执行任何阈值增量之前返回。 每个阈值都为零，因此每个输入比较都是错误的，并且每个单调程序都返回零。 例如，```
1 3 0
0
1
2
```产生`0`，这正是成功程序所需的数量。 

为了`s = m`，算法不断处理增量，直到每个程序都成为一个。 每个处理列的最终阈值可以达到`m`。 为了```
2 3 3
1 2 1
1 2 1
1 2 1
0 0
1 1
2 2
```第一个阈值最终变成`3`，但 AND 输出尚未为 1，因为第二个输入仍为零。 然后第二个阈值达到`1`,`2`，最后`3`。 每行的第二个输入在其相应的事件中变为 1，并且所有三个最终输出都变为 1。 返回的向量是`3 3`。 

为了`n = 1`，没有传播树。 每个程序中唯一的价值就是它的输入。 和```
1 4 2
0
1
2
3
```临界点`2`使前两个比较完全正确。 算法返回`2`直接地。 

对于与门，单个改变的输入可能没有效果。 在```
2 3 1
1 2 1
1 2 1
1 2 1
0 0
1 1
2 2
```第一列达到阈值后`3`，每个第一个输入都是 1，但每个第二个输入保持为零。 所有三个 AND 输出仍然为零。 当第二列达到阈值时`1`，第一行的第二个输入更改为 1，其 AND 输出更改为 1，并且全局计数变为 1。 传播代码正好处理这种依赖性。 

对于或门来说，改变一个输入就足够了。 在```
2 3 2
1 2 2
1 2 2
1 2 2
0 0
1 1
2 2
```将第一个阈值从零提高到一会将第一行更改为`0 or 0`到`1 or 0`，所以它的最终结果立即变为 1。 将其提高到 2 也会激活第二行，从而在不触及第二阈值的情况下给出所需的 2 计数。 

最后一个微妙的情况是一条输出已经变成 1 的指令。 仅当程序允许重复输入时，稍后的输入更改才可能通过另一个依赖项到达相同的指令，但问题明确禁止这样做。 即使不依赖此限制，也会检查`vals[out_pos]`在重新计算之前是有用的防御逻辑。 一旦指令为 1，单调性就保证了以后的任何更改都不能使其为零，因此通过该指令的传播可以停止。
