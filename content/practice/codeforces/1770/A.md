 **标签：** 暴力、贪婪
 **求解时间：** 3m
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们从白板上放置的一系列数字开始。 然后我们得到一系列替换值。 每个替换操作都允许我们选择任何一个白板并用操作中的新值覆盖其当前值。 

所有操作都必须使用，但是我们可以自由选择每次更新哪个白板，并且同一个白板可以多次更新。 目标是在应用所有替换后最大化板上写入的值的最终总和。 

一个关键的观察结果是，只有每个板上的最终值很重要，而不是应用操作的顺序。 每个操作都贡献一个值，该值最终将被分配到某个地方。 

自从$n, m \le 100$，约束允许直接的贪心推理。 任何解决方案直至$O(nm)$或者$O(m \log m)$很容易就足够了。 

一个微妙的边缘情况是$m > n$，这意味着某些板将被多次覆盖。 另一个是当$m < n$，这意味着一些原始值从未被触及。 一个天真的错误是假设每个操作都必须进行到不同的板，这是错误的并且会导致低估灵活性。 

## 方法

 蛮力方法将模拟分配每个的所有方法$m$价值观$n$板。 对于每个操作，我们选择其中之一$n$板，导致$n^m$的可能性。 即使是为了$n = m = 100$，这太大了。 

关键的简化来自于认识到最终配置仅取决于两组数字：初始棋盘值和我们决定从操作列表中应用的值。 每个操作只贡献一个值，我们可以选择它的去向。 这意味着我们正在有效地决定哪些最终值取代哪些初始值。 

为了最大化总和，我们应该保留较大的初始值，除非它们可以被更大的运算值替换。 由于每个操作值最多只能使用一次，因此最佳策略简化为在所有可用候选值中选择最大可能的值，并将它们放置到受益最大的板上。 

看到这一点的一个简洁方法是我们正在构建一个最终的大小多重集$n$，我们从哪里开始$a_i$并且最多可以替换$m$元素使用$b_j$。 仅当每次替换增加总和时才应使用，并且在所有选择中我们总是更喜欢更大的值。 

这导致对两个数组进行排序并贪婪地匹配最大的$b_j$具有最小的值$a_i$价值观。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力分配| 指数|$O(n)$| 太慢了|
 | 排序+贪心替换|$O(n \log n + m \log m)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 对初始数组进行排序$a$按升序排列，以便我们可以轻松识别最容易改进的最小值。 原因是替换一个小的值会产生最大的边际收益。 
2. 对替换值进行排序$b$按降序排列，这样我们就可以首先使用最强的可用改进。 这确保了我们永远不会在几乎没有什么好处的位置上浪费大量价值。 
3. 同时迭代两个数组，比较剩余的最小的$a[i]$剩余最大的$b[j]$。 如果$b[j] > a[i]$， 代替$a[i]$和$b[j]$。 否则，停止使用进一步的替代品，因为所有剩余的$a[i]$甚至更大。 
4. 继续这个过程，直到我们耗尽$b$或者达到没有替代品可以改善总和的程度。 生成的数组代表操作的最佳分配。 
5. 计算修改后的数组的最终总和。 

### 为什么它有效

 正确性依赖于交换论证。 假设我们有一个最佳解决方案，其中较小的替换值被分配给较小的$a[i]$，而较大的重置值要么未使用，要么分配在其他地方。 交换这些分配永远不会减少总和，而且可能会增加总和。 重复这个推理会得到一个结构，其中最大的$b$值与最小的匹配$a$每当有利时就值，这正是贪婪过程所构造的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    a.sort()
    b.sort(reverse=True)
    
    i = 0
    j = 0
    
    while i < n and j < m:
        if b[j] > a[i]:
            a[i] = b[j]
            i += 1
            j += 1
        else:
            break
    
    print(sum(a))
```实现直接遵循贪婪策略。 排序$a$使我们能够始终首先尝试改善最薄弱的位置。 排序$b$按降序排列可确保我们尽早使用最强的升级。 

一旦无法改进，循环就会停止，这样可以避免在所有剩余的情况下进行不必要的比较$a[i]$已经比剩余的大了$b[j]$。 最终总和是直接根据更新后的数组计算的。 

## 工作示例

 考虑输入$a = [1,2,3]$和$b = [4,5]$。 排序后我们比较一下$1$和$5$，替换掉，然后比较$2$和$4$，更换它，然后停止。 结果数组是$[5,4,3]$。 

| 步骤| 一个（状态）| b 指针 | 行动|
 | ---| ---| ---| ---|
 | 1 | [1,2,3]| 5 | 将 1 替换为 5 |
 | 2 | [5,2,3]| 4 | 将 2 替换为 4 |
 | 3 | [5,4,3]| 停止| 没有改善|

 最终总和是$12$，匹配最优配置。 

为了$a = [10,10]$和$b = [1,2]$，排序给出$a$不变并且$b = [2,1]$。 因为即使是最大的$b$不大于最小的$a$，没有发生替换，总和仍然存在$20$。

 ## 边缘情况

 当$m = 0$，不发生替换，输出只是$a$。 该算法会处理这个问题，因为循环永远不会执行。 

当所有$b_j \le \min(a_i)$，不会发生替换，因为第一次比较立即失败，确保我们不会减少总和。 

什么时候$m > n$，只有最大的$n$有用值来自$b$曾经被使用过，因为循环一旦全部停止$a[i]$已被考虑。
