 ## 解决方案
 ## 问题理解

 视频时长为`c`秒。 看一秒视频消耗`a`数据单位，而互联网连接仅下载`b`每秒单位。 自从`a > b`，立即启动是不可能的，因为数据消耗的速度比到达的速度快。 

假设观众等待`t`按播放键前几秒。 那时他们已经下载了`b · t`数据单位。 播放开始后，下载继续以相同的速率进行。 目标是找到最小的整数`t`这样在播放过程中的每个时刻，下载的数据量至少与观看时已经消耗的数据量一样大。 

限制非常小。 所有三个值最多为 1000。即使是检查许多候选等待时间的算法也能在限制内轻松运行。 挑战不是表现，而是正确表达条件。 

一个常见的错误是仅检查播放结束时是否可以下载整个视频。 考虑：```
4 1 1
```如果我们等待 2 秒，那么在播放结束时我们已经下载完毕`1·(2+1)=3`单位，仍然不足。 等待 3 秒正好得到 4 个单位。 答案是3。 

另一个微妙的情况是瓶颈发生在最后而不是开始附近。 例如：```
2 1 10
```等待4秒似乎很近，因为播放可以顺利开始。 然而，到第二次观看结束时，仅下载了 18 个单元，而需要 20 个单元。 正确答案是 5。 

仅检查播放开始的粗心模拟将错误地接受此类情况。 

## 方法

 直接的暴力策略是尝试等待时间`t = 0, 1, 2, ...`并测试是否可以播放。 

对于固定的`t`， 让`x`是已经观看的秒数。 此时，下载的数据等于```
b · (t + x)
```消耗的数据等于```
a · x
```播放有效，如果```
b · (t + x) ≥ a · x
```对于每一个`x`从`0`到`c`。 

检查全部`c + 1`每个候选人的时刻`t`之所以有效，是因为限制很小。 即使尝试 1000 次等待并每次检查 1000 个时刻，也只需要大约一百万次操作。 

关键的观察是不等式可以简化：```
b·t + b·x ≥ a·x
b·t ≥ (a-b)·x
```自从`a > b`，右侧增加为`x`增加。 最难满足的时刻是最大可能的值`x`，即`x = c`。 

因此，不需要每时每刻都检查，只需要```
b·t ≥ (a-b)·c
```答案是最小的整数`t`满足这个不等式：```
t = ceil((a-b)·c / b)
```这将整个问题简化为单个算术计算。 

| 方法| 时间复杂度| 空间复杂度| 判决|
 | --- | --- | --- | --- |
 | 蛮力 | O(c·答案) | O(1) | O(1) | 已接受 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`a`,`b`， 和`c`。 
2. 重写观看时间的播放条件`x`:```
b·(t+x) ≥ a·x
```3.重新排列：```
b·t ≥ (a-b)·x
```左边是恒定的，右边是随着增长的`x`。 
4. 自从`a > b`，右侧的最大值出现在`x = c`。 
5、要求：```
b·t ≥ (a-b)·c
```6. 计算满足不等式的最小整数：```
t = ceil((a-b)·c / b)
```7. 输出`t`。 

### 为什么它有效

 对于任何观看时长`x`，播放恰好在以下情况下可行```
b·t ≥ (a-b)·x.
```因为`a-b`为正，右侧单调增加`x`。 如果不等式对于最大可能值成立`x = c`，它自动适用于每个较小的值`x`。 因此检查视频的结尾是充分且必要的。 满足最终不等式的最小整数等待时间恰好是```
ceil((a-b)·c / b).
```## Python 解决方案```python
import sys
input = sys.stdin.readline

a, b, c = map(int, input().split())

need = (a - b) * c
answer = (need + b - 1) // b

print(answer)
```变量`need`存储播放开始前必须弥补的总赤字。 在观看的每一秒中，消耗量恰好超过下载量`a - b`单位。 超过`c`秒，赤字累积到`(a - b) · c`。 

等待`t`秒下载`b · t`单位提前。 我们需要：```
b·t ≥ need
```表达式```
(need + b - 1) // b
```计算上限`need / b`使用整数运算。 这避免了浮点计算并消除了任何舍入问题。 

限制很小，但使用整数数学既干净又数学精确。

 ## 边缘情况

 考虑：```
3 2 1
```播放期间累积的赤字为：```
(3-2)·1 = 1
```该算法计算：```
ceil(1/2) = 1
```等待 0 秒将立即失败，因为消耗开始速度比下载速度快。 等待 1 秒即可提供足够的缓冲。 

现在考虑：```
5 2 4
```赤字为：```
(5-2)·4 = 12
```自从```
12 / 2 = 6
```已经是一个整数，答案正好是 6。这个例子验证了当除法精确时，上限公式不会意外地增加一秒。 

最后，考虑最大可能值：```
1000 1 1000
```赤字变为：```
(1000-1)·1000 = 999000
```答案是```
999000
```所有算术都适合标准整数类型，并且公式仍然有效，无需任何特殊处理。
