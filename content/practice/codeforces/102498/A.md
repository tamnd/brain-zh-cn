 ## 解决方案
 ## 问题理解

 我们在坐标平面上有一个起点、一个目的地和几个可能的餐馆。 旅行者以每秒一个单位距离的恒定速度移动，并且在到达目的地之前必须恰好访问一家餐馆。 去餐馆会增加固定的等待时间，因为吃饭需要花费已知的秒数。 任务是选择总行程时间最短的餐厅。 

对于位于`(x_i, y_i)`，总时间是从出发地到那家餐厅的距离，加上吃饭的时间，再加上从那家餐厅到目的地的距离。 由于运动速度为一，欧氏距离直接代表行进时间。 答案是所有餐厅中该值的最小值。 

坐标的绝对值以 1000 为界，因此距离最多为几千个单位。 餐馆的数量可以达到 1000 家。这是一个足够小的输入大小，可以轻松地检查每家餐馆一次。 尝试每一对餐厅的解决方案已经是不必要的，因为唯一的选择是访问哪一家餐厅。 

一个常见的错误是只比较到目的地的直接距离而忽略了吃饭时间。 距离较远、等待时间较短的餐厅可能是最佳选择。 

例如：```
0 0 10 0
2
5 0 100
8 0 1
```第一家餐厅提供`5 + 100 + 5 = 110`，而第二个给出`8 + 1 + 2 = 11`。 选择最近的餐厅会给出错误的结果。 

另一个边缘情况是最好的餐厅不在起点和目的地之间。 如果餐厅的就餐时间足够短，则可以先移走一条路线。```
0 0 5 0
1
0 5 1
```时间是`sqrt(25) + 1 + sqrt(50) = 8.071067811865476`。 仅考虑位于直接段上的餐馆的解决方案将错误地拒绝唯一可能的餐馆。 

精度也很重要。 坐标是整数，但距离通常是无理数。 只要计算使用浮点数并且打印足够的位数，使用普通浮点格式打印就足够了。 

## 方法

 最直接的方法是独立检查每家餐厅。 对于每一个，计算从出发点到餐厅的距离，加上餐厅的就餐时间，然后加上从餐厅到目的地的距离。 所有餐厅中最小的值就是答案。 这种方法是正确的，因为每个有效旅程都必须选择一家餐厅，因此检查每个可能的选择涵盖了整个解决方案空间。 

蛮力方法已经具有与最优解决方案相同的结构，因为餐馆之间不存在隐藏的交互。 没有理由去两家餐厅，去一家餐厅的费用也不依赖于其他餐厅。 和`n = 1000`，这只需要 1000 次距离计算，这是微不足道的。 

每个餐厅都可以独立评估的观察结果让我们将问题简化为简单的最小搜索。 重要的是要认识到这里不存在寻路问题。 城市坐标不包含障碍物或限制，因此任意两点之间的最短路径始终是直线段。

 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 已接受 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取起点和终点。 存储它们是因为每个餐厅计算都需要相同的两个端点。 
2. 用一个非常大的值初始化答案。 这代表了在检查任何餐厅之前迄今为止找到的最佳路线。 
3. 对于每个餐厅，使用欧几里得距离公式计算从起点到餐厅的距离。 添加餐厅的就餐时长以及从餐厅到目的地的距离。 
4. 将此路线长度与当前答案进行比较，如果该餐厅给出的总时间较小，则替换答案。 
5. 打印最终的最小值，并保留足够的小数位以满足精度要求。 

这种方法有效的原因是整个问题中唯一的决定是餐厅的选择。 一旦选择了一家餐厅，到​​达然后离开它的最佳方式始终是直线，因为移动不受限制。 该算法对每个可能的选择只检查一次，因此它保留的最小值就是真正的最佳路线。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

def solve():
    xs, ys, xt, yt = map(int, input().split())
    n = int(input())

    ans = float("inf")

    for _ in range(n):
        x, y, t = map(int, input().split())

        first = math.hypot(xs - x, ys - y)
        second = math.hypot(xt - x, yt - y)

        ans = min(ans, first + t + second)

    print("{:.15f}".format(ans))

if __name__ == "__main__":
    solve()
```解决方案直接遵循算法。`math.hypot`使用它代替手动计算平方根，因为它清楚地表达了欧氏距离公式，并且避免了不必要的中间代码。 

答案从无穷大开始，因此第一家餐厅总是取代它。 每个餐厅都是独立处理的，计算完餐厅信息后不需要存储任何餐厅信息，从而保持内存使用恒定。 

进食时间是一个整数，但它被添加到浮点距离上。 Python 会自动将结果转换为浮点值，并保留所需的精度。 不存在溢出风险，因为坐标限制使所有平方距离都非常小。

 ## 边缘情况

 问题理解的第一个边缘情况是附近有一家但速度慢的餐馆。 为了：```
0 0 10 0
2
5 0 100
8 0 1
```该算法会评估这两种选择。 第一个给出`110`，第二个给出`11`，因此存储的最小值变为`11`。 Since the eating time is included in the same expression as the distances, the algorithm does not fall into the trap of selecting the closest restaurant.

 The second edge case is a restaurant outside the direct path:```
0 0 5 0
1
0 5 1
```该算法计算到餐厅的距离为`5`, 增加进食时间`1`，并添加最终距离`sqrt(50)`。 它从不按位置过滤餐厅，因此它正确返回大约`8.071067811865476`。 

最后的边缘情况是距离不是整数时。 例如，对角线移动的样本包含平方根。 该算法将所有计算保留为浮点值，并在小数点后打印十五位数字，这足以满足所需的误差容限。
