 ## 解决方案
 ## 问题理解

 我们在山间空地上有一棵扎根的树。 清算`1`是根，并且所有其他空地都有一个位于山上较高的父级。 移动仅从一个节点到其子节点之一，因此当某些直升机放置在其子树中时，空地可以准确地到达直升机。 

任务是选择地点`k`直升机，以便其下方至少有一个选定节点的空地数量尽可能多。 输入给出每个节点的父节点`2`到`n`，输出是可以到达直升机的最大可能空地数量。 

约束条件`n <= 300000`彻底改变了我们可以使用的解决方案类型。 保留有关许多子树或许多选择的信息的动态规划解决方案通常会太大。 甚至`O(n log n)`很舒服，同时又接近`O(nk)`或者`O(n^2)`是不可能的，因为树可以包含数十万个顶点。 

一些细节会让天真的想法变得危险。 第一个陷阱是选择任意内部顶点。 放置在内部顶点的直升机始终可以更深入地移动到其后代叶子之一，而不会失去任何覆盖的空地，因为每个可以到达旧位置的祖先也可以到达更深的位置。 第二个陷阱是假设最深的`k`按深度排列的顶点本身就足够了。 分数不是深度的总和，因为不同的直升机共享到根的路径。 例如，放置在不同分支的两架直升机可能覆盖同一条长路径上多于两架的直升机。 

考虑输入：```
5 1
1 2 3 4
```该树是由五个节点组成的链。 使用一架直升机，将其放置在节点处`5`涵盖了所有空地，所以答案是`5`。 仅将叶子错误地计数为一个可能的被覆盖节点的方法将在此失败。 

另一个重要的案例是明星：```
5 2
1 1 1 1
```根下面有四片叶子。 两架直升机可以覆盖根部和选定的两片叶子，给出答案`3`。 简单地添加两个选定叶子的深度的方法就可以计算`2`，而真正的答案更大，因为根是共享的。 

最后一种极端情况是有用的目的地比直升机少。 在一条链中，将一架直升机放在底部后，每增加一架直升机就没有任何贡献。 该算法必须允许零额外贡献，而不是假设每架直升机都会增加答案。 

## 方法

 一种直接的方法是尝试每组可能的直升机位置并计算覆盖了多少个祖先。 这是正确的，因为它会检查每个有效的展示位置。 然而，即使选择`k`之间的位置`n`节点已经提供了巨大的搜索空间。 对于一棵树来说`300000`顶点，这远远超出了我们所能探索的范围。 

更实际的第一个改进是观察直升机应放置在树叶中。 如果直升机位于内部节点中，则将其移动到任何后代叶子会保留所有被覆盖的节点，并可能覆盖更多节点。 这将问题转化为选择从叶子到根的路径。 

下一个常见的想法是对选定的叶子进行动态规划。 对于小树，我们可以存储哪些叶子已经被选择以及它们的路径有多少重叠。 问题是叶子的数量也可能很大，因此状态空间变得太昂贵。 

关键的观察结果是，通过查看当前未覆盖的最深顶点，始终可以找到下一个直升机的最佳位置。 想象一下最深的顶点`v`未选择。 沿着路径从`v`向根部移动，直到到达已被选定直升机覆盖的第一个顶点。 将所选直升机替换为`v`不能减少答案，因为替换覆盖了该交汇点之上的相同共享路径，并且还覆盖了以`v`。 因此，总是存在包含最深可用顶点的最优解。 

选择该顶点后，到根的路径上的每个顶点都会被覆盖，并且可以在将来的选择中忽略。 同样的论点再次适用于树的其余未覆盖部分。 重复这个过程`k`times 给出了最优的贪婪结构。 

剩下的挑战是有效地实施这个过程。 反复从最深的顶点走到根部会花费`O(nk)`。 相反，按深度递减的顺序处理一次顶点。 当考虑一个顶点时，仅向上遍历当前未标记的顶点并立即标记它们。 每个顶点最多标记一次，因此总工作是线性的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 叶上的动态规划 | 太大了`n = 300000`| 大| 太慢了 |
 | 贪婪的不相交集合跳跃 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 在读取树的同时计算每个空地的深度。 存储每个顶点的父顶点，因为稍后我们需要从顶点向上移动到根。 
2. 按深度递减对所有顶点进行排序。 首先考虑的顶点是能够提供最大可能的新覆盖范围的顶点。 该顺序与贪心证明相匹配，因为下一架直升机应始终放置在最深的剩余顶点处。 
3. 维护顶点上的不相交集合结构。`find(v)`返回路径上第一个未标记的顶点`v`向上。 当某个顶点被覆盖时，将其直接连接到其上方的下一个顶点。 这允许跳过树中已覆盖的部分。 
4. 对于排序顺序中的每个顶点，重复向上移动穿过未标记的顶点。 计算遇到的顶点数量并将它们标记为被覆盖。 这个计数是如果我们在那里放置下一架直升机所获得的额外空地数量。 
5. 保留所有获得的收益。 贪婪论证说，这种模拟产生的收益正是最优选择的贡献。 最终答案就是最大的数之和`k`收益。 

为什么它有效：

 不变的是，经过几次贪心选择后，标记的顶点正是已经放置的直升机覆盖的空地。 最深的未标记顶点始终是最佳的下一个选择，因为任何不使用它的解决方案都可以用这个更深的顶点替换路径上所选的顶点之一，而不会丢失任何现有的覆盖范围。 因此，每个贪婪步骤都可以从任意最优解转换为选择相同顶点的最优解。 重复这个交换论证证明算法产生的增​​益序列是最优的。 不相交集结构只是通过跳过已经覆盖的顶点来改变实现，因此它不会影响贪婪选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    parent = [0] * (n + 1)
    children = [[] for _ in range(n + 1)]

    if n > 1:
        p = list(map(int, input().split()))
        for i, x in enumerate(p, start=2):
            parent[i] = x
            children[x].append(i)

    depth = [0] * (n + 1)
    order = [1]
    for v in order:
        for u in children[v]:
            depth[u] = depth[v] + 1
            order.append(u)

    vertices = list(range(1, n + 1))
    vertices.sort(key=lambda x: depth[x], reverse=True)

    dsu = list(range(n + 1))

    def find(x):
        while dsu[x] != x:
            dsu[x] = dsu[dsu[x]]
            x = dsu[x]
        return x

    gains = []

    for v in vertices:
        cur = find(v)
        cnt = 0
        while cur != 0:
            cnt += 1
            dsu[cur] = find(parent[cur])
            cur = find(cur)
        gains.append(cnt)

    gains.sort(reverse=True)
    print(sum(gains[:k]))

if __name__ == "__main__":
    solve()
```该树使用子列表存储，因为我们需要从根开始遍历来计算深度。 迭代遍历避免了长度链上的递归深度问题`300000`。 

排序步骤完全按照贪心证明所需的顺序排列顶点。 我们不需要明确知道哪些顶点是叶子，因为交换参数允许直接选择最深的剩余顶点。 

不相交集数组的含义与通常的连接 DSU 略有不同。 它存储下一个未覆盖的祖先。 当顶点`x`被覆盖，我们设置`dsu[x]`到其父级上方第一个未覆盖的顶点。 未来搜索跳过`x`立即地。 

while 循环在整个执行过程中对每个顶点精确计数一次。 虽然看起来它可以为每个顶点行走一条路径，但每次成功的迭代都标记了先前未标记的清理，因此迭代总数的界限为`n`。 

答案是从`k`最大的收获。 在覆盖所有有用路径后，额外的直升机只会贡献零，这就是增益数组可能包含许多零的原因。
