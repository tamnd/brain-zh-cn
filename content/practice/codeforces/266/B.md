 ## 解决方案
 ## 问题理解

 我们给出一行用字符串表示的孩子，其中每个字符要么是男孩，要么是女孩。 该生产线随着时间的推移以离散的步骤演变。 在每一秒中，男孩站在女孩前面的每对相邻的对同时交换位置。 换句话说，所有有效的“BG”模式在同一秒内变成“GB”，并且所有交换都是并行发生的，而不是从左到右一个接一个地发生。 

任务是在应用此转换规则 t 秒后确定线路的配置。 

约束非常小，n 和 t 都最多为 50。这立即告诉我们，即使是简单的模拟也是可以接受的，因为最坏情况下的操作数量约为 n 乘以 t，即每次运行最多 2500 次交换检查。 即使我们每秒重复一次字符扫描，在 2 秒的限制下，总的工作量也是微不足道的。 

交换的同时性质产生了一种微妙的边缘情况。 如果我们从左到右处理并立即交换字符，我们可能会意外地在同一秒内重复使用更新的信息。 例如，考虑“BGBG”。 如果我们贪婪地交换第一对“BG”，我们会得到“GBBG”，然后下一对会被错误地评估，因为结构已经在中间发生了变化。 正确的解释要求一秒钟的所有交换都基于字符串的相同快照。 

另一种极端情况是互换重叠。 在像“BGB”这样的模式中，一步中只有第一对交换，中间的角色每秒最多参与一次交换。 这可以防止单个时间单位内的双重移动。 

## 方法

 对过程进行建模的最直接方法是逐秒进行模拟。 对于每个时间步，我们从左到右扫描字符串，每当看到“BG”模式时，我们将其交换为“GB”并跳过下一个位置，因为它已经作为交换的一部分移动。 这种方法与问题定义完全匹配并保持正确性，因为我们使用对当前状态的新传递一次模拟一整秒。 

这种强力模拟已经表现得足够好，因为每秒都需要对字符串进行一次传递，每秒的工作量为 O(n)。 在 t 秒内，总工作量为 O(n·t)，受限于 2500 次操作。 

不需要更高级的优化，因为约束不会推动我们渐近改进。 关键的见解不是加速计算，而是通过确保我们不会在一秒钟内链接更新来正确建模同时交换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 逐步模拟 | O(n·t) | O(n) | 已接受 |
 | 优化的全局运动模型| O(n) | O(n) | 已接受但没有必要 |

 ## 算法演练

 1. 从作为可变字符列表的初始队列开始。 这允许有效的交换。 
2. 重复该过程 t 秒。 每次迭代代表一个完全同步的转换步骤。 
3. 在每一秒中，使用从 0 开始的索引 i 从左到右扫描。 
4. 如果当前位置 i 和下一个位置 i+1 形成“B”后“G”的模式，则交换它们。 
5. 执行交换后，将 i 加 2 以避免重新处理新交换的字符。 
6. 如果位置 i 没有发生交换，则将 i 向前移动 1。 
7. 完成全扫描后，结果列表代表一秒后的队列。 
8. 继续，直到模拟完所有 t 秒。

交换后跳过索引的关键原因是交换的“GB”对不应在同一秒内重新考虑。 如果我们不跳过，同一个女孩可能会在一个时间步内参与多次交换，这违反了同时交换规则。 

### 为什么它有效

 正确性取决于每秒开始时的不变量，数组表示经过多次完整转换后的状态。 在一秒内，每次交换仅根据该秒的原始配置进行应用，因为我们从左到右扫描并确保一旦发生交换，该步骤就会消耗两个位置。 这可以防止同一秒内的级联效应，并确保所有交换完全对应于当前快照中不相交的“BG”对。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, t = map(int, input().split())
s = list(input().strip())

for _ in range(t):
    i = 0
    while i < n - 1:
        if s[i] == 'B' and s[i + 1] == 'G':
            s[i], s[i + 1] = s[i + 1], s[i]
            i += 2
        else:
            i += 1

print("".join(s))
```该解决方案将队列存储为列表，因此交换时间复杂度为 O(1)。 每一秒都是独立模拟的。 内部循环通过扫描一次并适当推进索引，仔细地强制执行交换基于每秒单个冻结配置的规则。 

一个常见的错误是从左到右更新字符串而不在交换后跳过索引。 这会导致对刚刚移动的角色进行双重处理，这违反了转换的同时性。

 ## 边缘情况

 一个关键的边缘情况是当交换相邻时，例如“BGB”。 在一秒钟内，只有第一个“BG”应该交换，产生“GBB”。 该算法可以正确处理此问题，因为交换索引 0 和 1 后，指针会跳转到索引 2，从而防止第二个字符在同一秒内参与另一次交换。 

另一种边缘情况是完全交替的字符串，如“BGBGBG”。 该算法确保每个不相交对的交换独立发生，并且交换后跳过可防止重叠损坏。 

最后，无操作情况（例如所有“G”或所有“B”字符串）确认了稳定性。 由于不存在“BG”模式，因此扫描在任何秒内都不会执行交换，并且在所有迭代中都保留不变状态。
