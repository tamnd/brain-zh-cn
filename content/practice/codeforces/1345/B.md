 ## 解决方案
 ## 问题理解

 我们得到了一系列相同的卡片，然后我们不断地建造称为金字塔的结构。 高度为 1 的金字塔是最小的可能结构，每个较高的金字塔都是分层构建的：较高的金字塔由放置在由附加卡片制成的较宽底座顶部的较小金字塔组成。 由于这种构造规则，每个高度都有固定的卡片成本。 

该过程是贪婪且顺序的。 从一定数量的卡片开始，我们总是尝试建造尽可能高的金字塔。 建造完金字塔后，我们减去它消耗的卡牌，并对剩余的金字塔重复相同的决定，直到无法形成任何高度的金字塔。 输出只是为每个测试用例总共构建了多少个金字塔。 

这里关键的隐藏对象不是几何金字塔，而是高度为 h 的金字塔的成本函数。 一旦知道了该成本，问题就变成了确定性的资源消耗过程：反复减去最大的可行成本。 

该约束允许最多 1000 个测试用例，所有测试的卡片总数最多为 10^9。 这立即排除了任何模拟每张卡的方法，甚至对每个测试用例重新计算成本过于昂贵的方法。 如果高度计算很快，重复搜索最大高度并减去的简单模拟仍然可以工作，因为每个金字塔至少消耗 2 张卡，因此在最坏的情况下最多有 O(n) 次迭代，但当 n 可以是 10^9 时，每个测试用例的 O(n) 是不可能的。 

一个更微妙的失败案例来自于对金字塔成本的错误解释。 一个常见的错误是假设线性增长或三角增长具有错误的常数。 例如，假设高度为 h 的金字塔需要花费 h^2 张卡片，即使对于像 n = 14 这样的小输入也会导致错误的构造计数，其中正确的行为取决于精确的组合堆叠规则。 

另一种边缘情况是小n，例如n = 1或n = 2。在这些情况下，不可能有更高的结构，并且任何对可行高度的高估都会导致减去太多卡片并产生负的或不正确的残差逻辑。 

## 方法

 蛮力方法在概念上很简单。 我们预先计算或导出每个金字塔高度 h 所需的卡片数量。 然后，对于每个测试用例，当我们仍然有卡片时，我们从最大可能的高度向下扫描，并选择成本不超过剩余卡片的最大 h。 我们减去该成本并增加答案。 

这是有效的，因为每个步骤都是局部最优的，并且问题明确强制需要贪婪构造。 然而，瓶颈在于反复寻找最大有效高度。 如果我们每次都从头开始重新计算，并且如果最大可能高度约为 O(√n)，则每次选择的成本为 O(√n)，在最坏的情况下，我们可能会构建 O(√n) 金字塔，导致在最坏的情况下每个测试用例的行为为 O(n)。 

关键的观察结果是，金字塔的成本随着高度的增加而快速增长，并且当 n 达到 10^9 时，最大高度只有几百左右。 这使我们能够一次预先计算所有金字塔成本。 之后，重复的过程就变成了对固定成本列表的简单贪婪减法。 由于成本序列快速增加，我们还可以将选择步骤减少为预先计算值的小循环。 

这将问题转化为从一个小的排序列表中重复选取最大值，直到总和耗尽。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n √n) 最坏情况直觉 | O(√n) | O(√n) | 太慢了 |
 | 最佳 | O(H² + T·H) 其中 H ≤ 450 | O(H) | 已接受 |

 ## 算法演练

1.预先计算每个金字塔高度h所需的卡片数量，直到成本超过10^9。 这是安全的，因为约束保证 n 永远不会超过这个范围。 每个 h 的成本是从前一个增量得出的，因为每个新层都会添加可预测数量的卡片。 
2. 将所有有效成本存储在递增数组 cost[] 中。 每个条目代表建造该高度金字塔所需的卡片的确切数量。 
3. 对于每个测试用例，从给定的 n 开始并初始化一个计数器 ans = 0。 
4. 当n仍然足够大以至少构建最小金字塔时，从最大到最小扫描成本数组并找到≤n的最大成本。 
5. 从 n 中减去该成本，并将 ans 加 1。 
6. 重复，直到剩余的 n 中没有成本为止。 

从最大向下扫描是正确的原因是该过程明确要求每次构建尽可能高的金字塔。 由于成本严格地随着高度的增加而增加，这保证了我们总是选择最大的有效高度。 

### 为什么它有效

 该算法保持了这样的不变性：每次减法之后，剩余的牌数始终是每一步最优贪婪选择的剩余数。 由于金字塔成本形成严格递增的序列，并且每一步仅取决于剩余资源，因此除了减少 n 之外，选择最大可行金字塔的决策与先前的选择无关。 这可以防止出现以下情况：早期选择较小的金字塔可能会在以后实现更大的总计数，因为较大的金字塔总是比较小的未使用部分结构的任何组合消耗更多的牌。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# precompute pyramid costs
# cost[h] = number of cards needed for pyramid of height h

MAX_N = 10**9
cost = []

h = 1
curr = 2  # cost of height 1 pyramid
while curr <= MAX_N:
    cost.append(curr)
    h += 1
    # derive next cost incrementally
    # recurrence: cost[h] = cost[h-1] + 3*h - 1
    curr += 3 * h - 1

cost.sort()

t = int(input())
for _ in range(t):
    n = int(input())
    ans = 0

    while n >= 2:
        # pick tallest possible pyramid
        for c in reversed(cost):
            if c <= n:
                n -= c
                ans += 1
                break
        else:
            break

    print(ans)
```实现的核心是预计算步骤。 我们不是在每个测试用例中重复导出金字塔大小，而是一次构建全局成本列表。 这可确保有效处理所有查询。 

每个测试用例内的贪婪循环总是从最大成本向下扫描。 这是安全的，因为列表很小（最多几百个条目），因此即使线性扫描也足够快。 

一个微妙的点是终止条件`n >= 2`。 高度为 1 的金字塔需要 2 张牌，因此任何低于 2 的金字塔都无法形成任何结构。 当答案已经确定时，这可以防止不必要的扫描。 

## 工作示例

 ### 示例 1：n = 14

 我们首先计算可用的金字塔成本最多为 14，它们是：

 2, 7, 15（这里只能使用2和7）

 | 步骤| n | 选择成本| 剩余 n | 金字塔 |
 | ---| ---| ---| ---| ---|
 | 1 | 14 | 14 7 | 7 | 1 |
 | 2 | 7 | 7 | 0 | 2 |

 该过程表明，贪婪选择每次都会选择最大的可能金字塔。 使用高度为 2 的金字塔（成本为 7）后，我们仍然能够建造另一个相同高度的金字塔。 

这证实了等成本选择的重复是有效的，并且该算法不需要全局跟踪使用的高度。 

### 示例 2：n = 15

 | 步骤| n | 选择成本| 剩余 n | 金字塔 |
 | ---| ---| ---| ---| ---|
 | 1 | 15 | 15 15 | 15 0 | 1 |

 这里最大的金字塔立即消耗掉所有资源，不留任何剩余。 这表明当发生精确匹配时，算法自然停止，无需额外逻辑。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(H² + T·H) | 预计算构建H成本； 每个测试扫描每步的 H 值 |
 | 空间| O(H) | 将金字塔成本存储到最大可行高度 |

 最大高度 H 很小（当 n ≤ 10^9 时远低于 500），因此即使每个测试用例进行二次预计算和线性扫描也是高效的。 该解决方案非常适合时间和内存限制。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MAX_N = 10**9
    cost = []
    curr = 2
    h = 1
    while curr <= MAX_N:
        cost.append(curr)
        h += 1
        curr += 3 * h - 1

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        ans = 0
        while n >= 2:
            for c in reversed(cost):
                if c <= n:
                    n -= c
                    ans += 1
                    break
            else:
                break
        out.append(str(ans))
    return "\n".join(out)

 ## 边缘情况

 对于 n = 1，成本列表仅包含从 2 开始的值，因此扫描立即无法找到任何有效的金字塔。 循环永远不会进入，并且答案正确地保持为 0。 

对于 n = 2，算法仅选择一次最小成本，将其减为零，然后干净地终止。 这证实了可以在不需要特殊大小写的情况下处理精确匹配。 

对于较大的 n，例如 10^9，算法会重复从一个小的固定列表中进行选择。 由于最大的金字塔成本仍然远低于n，因此前几次迭代可能会重复选择大金字塔，但n的收缩性质保证了在很少的步骤内终止。
