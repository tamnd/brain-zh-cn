 ## 解决方案
 ## 问题理解

 我们有一个（n \times n）有向网格。 圆盘只能向下移动一个单元格或向右移动一个单元格，因此每个圆盘都遵循从左上角到右下角的单调路径。 最初，所有 (d) 圆盘在 ((1,1)) 处形成有效的河内塔，最大的圆盘位于底部。 目标是将整个塔放在 ((n,n)) 处，而每个中间单元最多可容纳一个圆盘。 

输入以测试用例的数量开始。 每种情况都给出 (d)（圆盘数量）和 (n)（网格边长）。 对于每种情况，我们需要最少的移动次数或单词`impossible`。 所需的输出使用案例编号，而不是磁盘数量`Grid #...`标签，每个答案后有一个空行。 这些规则和所需的输出格式与原始竞赛声明一致。 

界限足够小，算术和简单的常量时间推理就足够了。 (d) 和 (n) 都最多为 100，因此 (O(dn^2)) 算法已经很简单了。 更重要的是，没有理由去模拟动作本身。 尝试搜索配置图的解决方案将是无望的，因为可能的磁盘位置的数量随着磁盘数量呈指数增长。 

第一个边缘情况是最小的网格。 用于输入`1`其次是`2 2`，在最大磁盘的最短路径之外正好有两个磁盘和一个可用的中间单元。 正确答案是`Grid #1: 4`。 使用严格不等式（例如 (d < (n-1)^2+1)）的粗心实现会错误地声明这是不可能的。 

第二个边缘情况是精确的容量边界。 对于(n=3)，最大可行磁盘数为(1+(3-1)^2=5)。 因此`5 3`可以在 (5\cdot4=20) 步中求解，而`6 3`是不可能的。 使用 (d \ge (n-1)^2+1) 作为不可能条件的实现会错误地拒绝第一种情况。 

第三种边缘情况是大量磁盘和小网格。 为了`100 8`，容量只有(1+7^2=50)，所以答案不可能。 不能仅仅因为每个单独的磁盘都有到目的地的有效单调路由而忽略磁盘的数量。 

## 方法

 直接方法会将每个完整的磁盘排列建模为一个状态，并从初始塔执行 BFS。 BFS 是正确的，因为每个合法的移动都会花费 1，因此第一次到达目标配置时会给出最小的移动次数。 问题在于状态空间的大小。 即使我们使用非常宽松的上限，即每个 (d) 磁盘可以独立占据 (n^2) 个单元格之一，也有 ((n^2)^d=n^{2d}) 个候选位置分配。 对于 (d=n=100)，这是 (100^{200}=10^{400}) 个候选者。 即使在考虑每个状态产生的移动之前，对这样的空间进行搜索也是完全不可行的。 

蛮力之所以有效，是因为它明确遵守排序和容量规则，但它会失败，因为几乎所有配置空间都是不相关的。 有用的观察结果是，每个磁盘从起点到目的地的最短距离完全相同。 由于圆盘只能向右或向下移动，因此它需要恰好 (n-1) 次向下移动和 (n-1) 次向右移动，最少需要

 [
 2（n-1）
 ]

 移动。 

这立即给出了下界

 [
 d\cdot2(n-1)
 ]

 对于整个拼图。 如果我们可以安排一个合法的解决方案，其中每个圆盘仅沿着最短路径移动，那么这个下限也是答案。 

最大的磁盘决定了这是否可能。 在最大的圆盘离开 ((1,1)) 之前，每个较小的圆盘都必须离开该钉子。 一旦最大的圆盘开始移动，它最终必须首先到达目的地，因为目的地塔必须从最大到最小重建。 因此我们需要为最大的磁盘保留一条路径。 

从 ((1,1)) 到 ((n,n)) 的最短单调路径访问 (2n-1) 个单元。 例如，我们可以保留整个顶行，然后是最右边的列。 当最大的磁盘使用该路径时，较小的磁盘不能占用任何这些单元。 

剩余细胞数为

 [
 n^2-(2n-1)
 =(n-1)^2。 
]

 这些单元正是较小磁盘可用的临时区域。 我们有 (d-1) 个较小的磁盘，因此当

 [
 d-1\le (n-1)^2,
 ]

 或同等地，

 [
 d\le n^2-2n+2。 
]

 当该条件成立时，较小的盘可以布置在远离保留路径的区域内，并且可以对移动进行排序，使得较小的盘在较大的盘需要它们之前被移开。 然后，每个磁盘可以沿着单调最短路线继续到达目的地。 这是标准解决方案背后的关键构建。 

因此，答案只有两种可能。 如果(d>n^2-2n+2)，则该谜题是不可能的。 否则最小值正好是 (2d(n-1))。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(d,n^{2d})) 候选状态工作 | (O(n^{2d})) | 太慢了|
 | 最佳| 每个测试用例 (O(1)) | (O(1)) | (O(1)) | 已接受 |

 ## 算法演练

 1. 阅读(d)和(n)。 我们唯一需要的信息是圆盘的数量和网格的大小，因为几何形状是完全规则的。 
2. 计算可用于临时存储的单元格数量：

 [
 \text{自由} = n^2-(2n-1)=(n-1)^2。 
]

 最大圆盘的最短路径占用 (2n-1) 个单元，因此每个其他中间单元都可能容纳一个较小的圆盘。 

1. 检查所有 (d-1) 个较小的磁盘是否适合该临时区域。 条件是

 [
 d-1\le(n-1)^2。 
]

 等价地，当

 [
 d\le n^2-2n+2。 
]

 相等情况是有效的，因为临时区域可以恰好包含所有 (d-1) 个较小的磁盘。 

1. 如果条件不成立，则打印`impossible`。 有太多较小的磁盘，无法清除起始桩，同时为最大的磁盘留下完整的最短路径。 
2. 否则，每个圆盘都可以精确地使用 (2(n-1)) 次移动来移动。 将该距离乘以 (d)：

 [
 \text{答案}=d\cdot2(n-1)。 
]

 不可能有更大的值作为下界，因为每个磁盘必须至少进行那么多移动，并且临时区域构造达到了界限。 

### 为什么它有效

 每个圆盘必须从 ((1,1)) 移动到 ((n,n))，唯一合法的方向是向右和向下。 因此每个圆盘至少需要 (2(n-1)) 次移动。 最大的圆盘必须具有无障碍的单调路线，因为直到所有较小的圆盘都离开起始桩之前它才能移动，并且它必须在任何较小的圆盘可以堆叠在其上之前到达目的地。 

最大圆盘的最短路径包含 (2n-1) 个单元。 其他 (n^2-(2n-1)=(n-1)^2) 个单元恰好在 (d-1\le(n-1)^2) 时形成足够的临时存储空间。 当这种不等式成立时，较小的磁盘可以保留在保留路径之外，同时保留其到目的地的单调最短路径。 因此每个圆盘都可以达到 (2(n-1)) 次移动的下界。 如果不等式失败，则没有足够的单元格来清除起始塔而不阻塞最大圆盘的每条最短路径，因此该难题无法解决。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    g = int(input())
    out = []

    for case in range(1, g + 1):
        d, n = map(int, input().split())

        capacity = n * n - 2 * (n - 1)

        if d > capacity:
            out.append(f"Grid #{case}: impossible")
        else:
            moves = d * 2 * (n - 1)
            out.append(f"Grid #{case}: {moves}")

        out.append("")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```程序首先读取网格数并独立处理每一对 ((d,n))。 变量`capacity`是 (n^2-2(n-1))，这是最大可能的磁盘数，包括最大的磁盘本身。 

比较必须是`d > capacity`， 不是`d >= capacity`。 在相等的情况下，正好 (d-1=(n-1)^2) 个较小的磁盘适合可用的临时单元，因此实例仍然是可解的。 

如果实例可行，则答案是`d * 2 * (n - 1)`。 Python 整数具有任意精度，尽管这些限制无论如何都会使结果值很小。 

每个案例后面附加的空白字符串都会生成所需的空白行。 案例计数器独立于 (d)，因此输入如`2 2`在第一个测试用例上正确生成`Grid #1`， 不是`Grid #2`。

 ## 边缘情况

 最小的有效输入是`1`其次是`2 2`。 这里(n^2-2(n-1)=4-2=2)，所以(d=2)正好达到容量。 该算法采用可行分支并计算 (2\cdot2\cdot(2-1)=4)，产生`Grid #1: 4`。 这抓住了将平等视为不可能的常见错误。 

(n=3) 的精确边界是`5 3`。 容量为 (9-4=5)，因此算法接受它并计算 (5\cdot4=20)。 五个磁盘由一个最大的磁盘和四个较小的磁盘组成，与所选最短路径之外的四个临时单元完全匹配。 

立即不可能的情况是`6 3`。 容量仍为 5，但现在有 5 个较小的磁盘仅竞争 4 个临时单元。 测试`d > capacity`计算结果为 true，因此算法打印`Grid #1: impossible`。 这是针对相差一错误的最干净的测试。 

对于最大尺寸的情况`100 100`，容量为（10000-198=9802），所以100块磁盘是很容易实现的。 每个磁盘需要 (2(99)=198) 次移动，给出 (100\cdot198=19800)。 该算法不需要模拟任何这些移动，这正是解决方案在每个测试用例中保持恒定时间的原因。
