 ## 解决方案
 ## 问题理解

 每个测试用例描述了美国和俄罗斯两个国家的奖牌数量。 这六个整数依次为美国金、银、铜牌，其次是俄罗斯金、银、铜牌。 

有两种独立的方式来决定美国是否获胜。 下`count`排名中，只有奖牌总数很重要，因此我们比较三项奖牌数的总和。 下`color`排名中，奖牌类型有严格的优先级：金牌优先，金牌并列时才考虑银牌，金银双方并列时才考虑铜牌。 这正是三元组的字典顺序比较`(gold, silver, bronze)`。 

对于每个测试用例，我们打印原始的六个数字，然后打印`count`如果美国仅靠奖牌总数获胜，`color`如果美国仅凭奖牌颜色获胜`both`如果美国在两种制度下都获胜，并且`none`如果俄罗斯在这两种体系下都没有被击败。 每个结果后面有一个空行。 

该语句指定一个正数`n`测试用例并表示每个奖牌计数介于`0`和`500`。 这些界限使得每个算术运算都变得很小。 即使`n`一样大`10^5`或者更多，不需要排序、动态规划、图形遍历或任何取决于奖牌值的操作。 我们对每个测试用例执行恒定的工作量，因此总工作量随着用例的数量线性增长。 

声明中提供的示例包含五个六整数测试用例，但不显示领先的`n`，尽管书面输入描述说`n`应该存在。 下面的解决方案接受两种形式：官方`n`-前缀格式和示例的每个案例六个整数的格式。 这不会改变算法或其复杂性。 

一个常见的边缘情况是奖牌总数平局，而美国队则以颜色获胜。 例如，```
1
10 5 5 8 6 6
```美国有`20`奖牌和俄罗斯有`20`，所以美国并没有通过计数获胜。 不过美国队的金牌数更多，`10`相对`8`，所以正确的结果是`color`。 一个粗心的解决方案仅根据奖牌总数来决定答案将错误地拒绝美国队的彩色胜利。 

相反的情况也是可能的。 例如，```
1
8 5 5 10 4 3
```美国有`18`而俄罗斯则获得了奖牌`17`，所以美国按计数获胜。 然而，俄罗斯获得的金牌更多`10`相对`8`，因此美国失去了颜色排名。 正确的结果是`count`。 将两个排名系统视为等效的解决方案会导致这种情况错误。 

另一个微妙的情况是金领带必须用银来解决。 例如，```
1
5 8 1 5 7 10
```两国都有五枚金牌，因此金牌不能决定颜色排名。 美国队获得了八枚银牌，而俄罗斯队则获得了七枚，因此美国队以颜色获胜。 一旦白银打破平局，青铜就无关紧要了。 

当黄金和白银打成平手时，同样的逻辑也适用得更深一层。 例如，```
1
5 7 9 5 7 8
```金色和银色的数量相等，因此青铜色决定颜色排名。 美国队获得了九枚铜牌，而俄罗斯队则获得了八枚铜牌，最终美国队获得了胜利。 

最后，两个系统下必须产生精确的平局`none`，不是胜利。 例如，```
1
5 7 9 5 7 9
```总计数和所有三枚奖牌颜色都相同，因此严格意义上来说，两者的比较都没有更大。 

## 方法

 一种简单的方法是计算美国队和俄罗斯队的总数，然后比较三枚奖牌数，每次一枚，得出颜色排名。 这已经足以解决问题，因为每个测试用例只有六个输入值。 总的比较需要两次相加，颜色的比较最多需要3次比较。 

人们可能会描述一种更字面的暴力策略，即检查三种奖牌颜色的每种可能的顺序，并尝试确定哪种顺序与排名规则匹配。 只有`3! = 6`这样的顺序，因此即使这种方法在每种情况下最多执行恒定数量的操作。 和`n`测试用例，最坏的情况大致是`6n`订购支票，仍然是`O(n)`。 在规定的限制下，不存在会变得太慢的实际输入大小。 该问题的大小足够固定，因此有用的优化不是渐近改进，但首先要认识到不需要搜索或排序。 

关键的观察是颜色排名已经由顺序完全描述`(gold, silver, bronze)`。 我们不需要构建排名、对奖牌进行排序或为奖牌类型分配权重。 我们只是按字典顺序比较这两个三元组。 Python 的元组比较准确地表达了这个规则，尽管解决方案也可以显式地编写三个比较以使推理透明。 

蛮力思想之所以有效，是因为一种情况下的数据量是恒定的，但它通过考虑问题已经为我们排序的可能性而引入了不必要的工作。 颜色排名是一种直接的词典比较，这一观察结果将整个任务减少为两个恒定时间谓词，一个用于总计数，一个用于颜色。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 已接受，但不必要的工作 |
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取一个测试用例的六枚奖牌计数并保持原始顺序。 不改变地打印这些值是所需输出的一部分，因此没有理由稍后重建输入。 
2. 将美国队的奖牌总数计算为`ug + us + ub`俄罗斯的总数为`rg + rs + rb`。 放`wins_count`根据美国的总数是否严格更大。 平等并不是胜利，因为该声明问的是美国是否获胜，而不是美国是否打平。 
3. 比较三重奖牌`(ug, us, ub)`和`(rg, rs, rb)`按金、银、铜顺序。 如果美国的金牌数量较多，或者金牌数量与银牌数量较多，或者金银双方并列且铜牌数量较多，则美国在颜色排名中获胜。 
4. 合并两个布尔结果。 如果两者都为真，则打印`both`。 如果只有计数结果为真，则打印`count`。 如果只有颜色结果为真，则打印`color`。 如果两者都不成立，则打印`none`。 
5. 在测试用例结果后打印一个空行。 这与所需的输出结构相匹配，并且还使连续的测试用例在视觉上分开。 

关键的不变量是在总体比较之后，`wins_count`当美国总体上获得更多奖牌时，情况就是如此。 色彩对比后，`wins_color`当国家不同的第一个奖牌类型属于美国且数量较多时，情况正好如此。 由于每种可能的结果都是由这两个独立的谓词决定的，因此最终的四向分类不可能是错误的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, sys.stdin.buffer.read().split()))

    if not data:
        return

    # The written statement includes n, while the supplied sample
    # omits it. Support both formats.
    if len(data) >= 1 and (len(data) - 1) % 6 == 0 and data[0] == (len(data) - 1) // 6:
        n = data[0]
        start = 1
    else:
        n = len(data) // 6
        start = 0

    out = []

    for i in range(n):
        a = data[start + 6 * i:start + 6 * i + 6]
        ug, us, ub, rg, rs, rb = a

        usa_total = ug + us + ub
        russia_total = rg + rs + rb
        wins_count = usa_total > russia_total

        if ug != rg:
            wins_color = ug > rg
        elif us != rs:
            wins_color = us > rs
        else:
            wins_color = ub > rb

        if wins_count and wins_color:
            result = "both"
        elif wins_count:
            result = "count"
        elif wins_color:
            result = "color"
        else:
            result = "none"

        out.append(" ".join(map(str, a)))
        out.append(result)
        out.append("")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```程序首先一次性读取所有整数。 这避免了依赖于测试用例是否物理上每行排列一个，因为空格是整数输入的唯一相关分隔符。 

格式检测处理书面陈述和提供的样本之间的差异。 如果第一个数字等于剩余的六个整数组的数量，则将其解释为`n`。 否则，所有整数都被视为奖牌数据。 在官方格式下，输入以`5`其次是三十枚奖牌价值被认定为五种情况。 根据提供的样本格式，三十枚奖牌价值被识别为五种情况。 

对于每种情况，六个值被分解为三个美国计数和三个俄罗斯计数。 总排名采用普通整数加法和严格的`>`比较。 

颜色排名故意编写为显式条件比较，而不是依赖于元组语法。 如果金牌不同，则会立即做出决定，因为银牌和铜牌不再重要。 如果黄金打成平手，那么白银也会受到同样的待遇。 只有当两者打成平手时我们才会比较铜牌。 这直接反映了排名规则，并避免意外地将奖牌类型视为同等价值。 

最终的条件链处理两个排名的四种可能的组合。 Python 中不存在整数溢出问题，即使在固定宽度语言中，最大总数也仅为`1500`，因为每个国家最多有三枚奖牌数`500`。

 ## 边缘情况

 第一个边缘情况是精确平局。 为了```
1
5 7 9 5 7 9
```两个总数均为`21`， 所以`wins_count`是假的。 金色打成平手，银色打成平手，青铜也打成平手，所以最终的颜色对比是`9 > 9`，这是错误的。 两个谓词都是假的，给出`none`。 非严格比较，例如`>=`会错误地将其归类为美国的胜利。 

奖牌总数平局并不妨碍颜色获胜。 为了```
1
10 5 5 8 6 6
```两国都有`20`奖牌，因此计数比较失败。 金色立即决定颜色排名，因为`10 > 8`, 给予`color`。 一旦金牌不同，该算法就不需要检查银牌或铜牌。

1
8 5 5 10 4 3
```美国有`18`奖牌和俄罗斯有`17`，所以计数是美国获胜。 黄金则反其道而行之`8 < 10`，所以颜色是一种损失。 这两个布尔值变成`true`和`false`，生产`count`。
