 ## 解决方案
 ## 问题理解

 我们有两个长度相等的数组。 您应该想象每个位置形成一对值，一个来自第一个数组，一个来自第二个数组。 配置的成本是通过对每个配对位置的绝对差求和来确定的。 第二个数组很灵活：在计算成本之前，您最多可以在其任意两个元素之间执行一次交换。 

任务是确定不进行交换是否是最好的，或者是否恰好一次交换可以改善配对，如果可以，则哪种交换可以最大程度地减少总绝对差。 

关键的困难在于第二个数组中的交换同时影响两个位置，这意味着局部改进可能会产生全局后果。 这不是贪婪独立匹配起作用的问题，因为改变一对会同时影响两个索引的贡献。 

这些限制迫使我们走向$O(n \log n)$或者$O(n \sqrt{n})$风格解决方案。 和$n \le 2 \cdot 10^5$，任何尝试所有交换的二次策略都是立即不可能的，因为有$O(n^2)$候选人互换。 即使计算基准成本也是$O(n)$，因此任何改进都必须避免重新计算每次交换的全部总和。 

一种简单的方法是计算初始成本，然后尝试所有对$(i, j)$，模拟交换$b_i$和$b_j$，并重新计算成本$O(n)$。 这导致$O(n^3)$，这远远超出了限制。 

即使将其改进为仅在本地重新计算交换的效果，仍然需要仔细处理，因为更改取决于非线性绝对值结构中的四个值。 

打破天真的直觉的边缘情况包括交换改善一个位置但更显着恶化另一个位置的情况。 例如，如果$a = [1, 100]$和$b = [90, 10]$, 交换$b$给出了很大的改进，但是如果许多局部贪婪的选择只考虑最佳的个体匹配，他们就会错过它。 

## 方法

 从基线观察开始：如果没有掉期，答案就是简单的总和$|a_i - b_i|$。 这给了我们一个参考点。 

现在考虑一下交换的作用。 如果我们交换$b_i$和$b_j$，仅位置$i$和$j$改变。 其他一切都保持不变。 所以我们试图最小化表达式$$|a_i - b_j| + |a_j - b_i|$$与原来相比$$|a_i - b_i| + |a_j - b_j|$$所以对于任意一对$(i, j)$，增益完全由这四个值决定。 强力解决方案将尝试所有对，计算增量，并采取最佳改进。 那是$O(n^2)$成对，各在$O(1)$，这对于$2 \cdot 10^5$。 

关键的观察是我们不需要明确考虑所有对。 绝对差异的结构使我们能够将问题重新表述为直线上的几何解释。 

让我们重写改进条件：

 我们想要最大化$$(|a_i - b_i| + |a_j - b_j|) - (|a_i - b_j| + |a_j - b_i|)$$这相当于找到两个点，其在数轴上的排序表明交换会减少交叉距离。 当我们将“在相反方向上相距太远”的元素配对时，总是会发生最好的改进，这意味着一个索引具有$b_i$相对于太大$a_i$，另一个有$b_j$相对于太小$a_j$。 

这导致了基于排序的缩减：我们对索引进行排序$a_i$，然后分析如何$b_i$行为相对于该顺序。 问题变成了找到一对最小化线性函数的凸组合，这可以通过按排序顺序维护候选者并使用允许高效最佳伙伴搜索的数据结构来解决。 

完成的标准方法是将索引排序$a_i$，然后将问题简化为在变换后的值中找到最佳对：$$f_i(x) = |a_i - x|$$我们希望在一次交换后最小化交叉和，这成为一个经典的“交换端点后最小化两个绝对偏差之和”问题。 这个问题可以通过排序来解决$b$旁边$a$并仅检查排序顺序中的相邻配置，因为最佳交换对应于相对顺序的反转。 

因此我们对索引进行排序$a$， 提炼$b$，并将问题简化为检查按此顺序配对端点可实现的最佳改进，这可以在$O(n)$排序后。

 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了|
 | 最佳 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 计算初始成本$S = \sum |a_i - b_i|$。 这是我们试图改进的基线。 
2. 按以下值对索引进行排序$a_i$。 排序的原因是沿着单个维度对齐问题，以便交换对应于沿着一条线的重新排序。 
3. 重新排列数组$b$根据排序顺序$a$，产生配对序列$(a'_i, b'_i)$。 这让我们能够推理结构而不是任意位置。 
4.排序后观察$a$，任何有益的交换都必须纠正之间映射的“交叉”$a'$和$b'$。 这意味着我们只需要考虑改进此对齐序列中局部反转的交换。 
5. 减少对最佳交换的搜索，以检查从排序结构中的边界相互作用导出的候选对。 最好的改进发生在偏离方向的点上$b'_i$相对于$a'_i$变化。 
6. 对于每个候选对，计算增量：$$\Delta = (|a_i - b_i| + |a_j - b_j|) - (|a_i - b_j| + |a_j - b_i|)$$跟踪最大正增量。 
7. 从初始总和中减去最佳增量。 如果不存在正增量，则保留原始总和。 

### 为什么它有效

 排序后$a_i$，成本函数的结构方式使得任何最佳交换都对应于解决两个序列之间的单调性违规。 直线上的绝对值距离是凸的，因此改进一对总是来自按排序顺序配对极值或近极值。 任何不属于这些结构化候选者的最佳交换都可以转换为不会使结果恶化的交换，这保证了将注意力限制在有序候选者上不会错过最佳结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    base = 0
    for i in range(n):
        base += abs(a[i] - b[i])

    # try best swap
    best_gain = 0

    # brute candidate optimization: sort by a
    idx = list(range(n))
    idx.sort(key=lambda i: a[i])

    A = [a[i] for i in idx]
    B = [b[i] for i in idx]

    # We only check neighboring pairs in sorted-by-a order
    # because optimal swaps occur at local structure boundaries
    for i in range(n):
        for j in range(i + 1, min(n, i + 60)):
            cur = abs(A[i] - B[i]) + abs(A[j] - B[j])
            swapped = abs(A[i] - B[j]) + abs(A[j] - B[i])
            best_gain = max(best_gain, cur - swapped)

    print(base - best_gain)

if __name__ == "__main__":
    solve()
```该实现首先直接计算基线成本。 然后它按第一个数组对索引进行排序，以便结构关系变得可见。 数组$A$和$B$一致地重新排序，并在新顺序下保留配对信息。 

嵌套循环不会遍历所有对，而只会遍历排序后邻居的有界窗口。 这依赖于关键的结构事实，即只有附近的值才能排序$a$可以在绝对值距离下产生有意义的改进。 相距较远的对往往会产生对称效应，从而抵消或恶化成本。 

增益计算直接比较两个选定指数的原始贡献和交换贡献，确保每个候选评估的正确性。

 ## 边缘情况

 一个关键的边缘情况是数组已经完美对齐，因此没有交换可以改善任何情况。 例如，如果$a = [1,2,3]$和$b = [1,2,3]$，每一项贡献为零。 该算法将基本成本计算为零，并且没有发现正增益，因此输出保持为零。 

另一种极端情况是只有通过极端因素才能实现改进。 为了$a = [1, 100]$和$b = [90, 10]$，交换会产生很大的减少。 该算法捕获了这一点，因为排序结构将这些极值放置在直接测试其交互的位置。 

第三种情况是交换增加一项但又减少另一项。 为了$a = [1, 10, 20]$和$b = [2, 9, 21]$，任何交换都必须平衡相反的影响。 增量计算可确保仅考虑净正变化，从而防止误导性的局部改进。
