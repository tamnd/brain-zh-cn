 ## 解决方案
 ## 问题理解

 我们被要求为基于固定位的格式设计一个自定义整数编码系统。 每个数字都使用前导 4 位选择器进行编码，后跟零到四个附加 4 位组。 这意味着每个值首先被分配 16 种可能的主要“模式”之一，每种模式决定两件事：读取多少个额外的 4 位组，以及解码后如何应用基本偏移。 

更具体地说，解码是这样工作的。 首先我们读取初始 4 位块，它选择一个表条目。 该条目告诉我们后面还有多少个 4 位块，并且还给出了偏移量。 然后我们将额外的块解释为固定长度 g 的以 16 为基数的数字，因此其范围从 0 到 16^g − 1。最后我们添加偏移量。 

关键的设计问题是我们必须为 16 个前缀中的每一个分配一对 (g, f)，这会产生 16 个不相交的可表示值“区间族”。 [x, y] 中的每个整数必须只能由一个前缀配置唯一地表示，并且我们希望分配此范围内的值，以便对给定序列 a1 … an 进行编码时使用尽可能少的 4 位组。 

所以每个前缀 i 对应一个块：

 整数集 [f_i, f_i + 16^g_i − 1]，编码成本为每个指定值 1 + g_i 组。 

挑战在于将区间 [x, y] 划分为最多 16 个不相交的段，每个段的大小限制为 16 的幂，并且每个段的每个元素的成本仅取决于其指数。 然后我们必须将 [x, y] 中的所有值分配给段，以便每个整数只被覆盖一次，同时最小化多重集 a1…an 的成本。 

约束 y − x ≤ 10^6 表明我们可以提供 O(range × 16) 或 O(range × log range) 动态规划解决方案。 主要困难在于16个前缀中的每一个都可以任意移动（通过f_i），因此分区并不固定在一个网格上； 这是一个灵活放置的加权分割问题。 

一种简单的方法会尝试将前缀分配给范围以及所有可能的块放置。 这是组合爆炸性的。 

如果假设通过局部频率进行贪婪分配或首先获取最大的块，则会出现微妙的失败情况。 例如，如果 x = 0、y = 15 并且序列严重偏向一个区域，则贪婪分配可能会分配一个大块来覆盖低频数字，同时在密集区域上浪费小成本表示，从而缺少最佳重用结构。 声明中的示例已经暗示，即使统一的块大小看起来很诱人，最佳解决方案有时也会对不同的前缀使用不同的 g 值。 

另一个微妙的问题是假设每个前缀必须对应于与 16 次幂对齐的连续区域。由于偏移量是自由的，因此这些段可以放置在数轴上的任何位置； 仅限制长度，不限制对齐。 

## 方法

 强力策略将尝试为 16 个前缀中的每一个分配 [0, 4] 中的 g 选择和偏移量 f，然后尝试将 [x, y] 中的每个整数分配给这 16 个间隔之一而不重叠。 即使忽略偏移量，这已经为 g 单独提供了 5^16 种可能性，并且对于每种配置，我们仍然需要解决最多 10^6 个整数的覆盖/分配问题。 这是完全不可行的。 

关键的观察结果是，每个使用的元素的成本结构是线性的：每个前缀 i 为分配给它的每个整数贡献固定成本 1 + g_i，容量为 16^g_i。 这暗示了一种“桶拟合”的解释：每个前缀都是一个具有容量和单位成本的容器，我们必须将 [x, y] 的整数打包到这些容器中而不重叠。

我们可以考虑扫描从 x 到 y 的整数行，并为每个前缀决定它将覆盖哪个段。 由于偏移量是任意的，因此实际的数字位置并不重要； 只有为每个 (g, f) 对分配多少个整数才重要。 因此，问题简化为将长度 L = y − x + 1 分割为最多 16 个块，其中每个块的大小为 16^g，成本与该大小成正比。 

这变成了有界背包式DP：我们希望使用最多16个项目来表示L，其中每个项目类型为g ∈ [0,4]，值为16^g，成本为(1+g)·16^g，但我们还有一个额外的约束，即16个前缀中的每一个都是不同的，这意味着我们不能任意多次重用单个配置； 相反，我们必须准确选择 16 个容量总和至少为 L 的作业，然后放置它们。 

更有用的重新表述是为每个前缀分配容量 c_i = 16^g_i 和每个元素的成本 w_i = 1 + g_i。 然后我们必须选择总和至少为 L 的 16 个容量，然后通过始终首先填充最便宜的每元素成本前缀来最佳地分配元素。 这本质上是选择容量后的贪婪分配，但选择容量本身是一个关于指数大小的有界整数划分问题。 

关键的见解是，由于只有 5 个可能的 g 值并且只有 16 个槽，因此我们可以 DP 确定每个 g 使用多少个前缀。 对于配置，我们知道总容量和总成本结构，然后我们通过最便宜的每单位成本块来模拟贪婪地填充 [x, y]。 这在小状态空间上产生了有效的优化。 

因此，问题简化为选择计数 c0…c4 总计为 16，计算所得容量和成本，并验证覆盖 L 的可行性，同时尊重唯一性并最小化序列权重的成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(5^16·10^6) | O(5^16·10^6) | O(10^6) | O(10^6) | 太慢了 |
 | 前缀类型上的最佳 DP | O(16^2) 或 O(16^3) | O(16^2) | O(16^2) | 已接受 |

 ## 算法演练

 1. 计算 L = y − x + 1，这是必须能够唯一表示的不同整数的数量。 我们将把这些整数中的每一个分配给一个前缀配置。 
2. 预先计算 g = 0..4 时的幂 p[g] = 16^g，因为带有参数 g 的每个前缀都可以精确编码 p[g] 值。 这是一个块的容量。 
3. 计算输入序列中每个值在区间 [x, y] 内的频率。 我们只关心每个整数的使用频率，因为每次出现的成本都会累积，因此频繁使用的值应该更喜欢更便宜的表示形式。 
4. 对于将 16 个前缀分配给计数 cnt[g]（有多少个前缀使用参数 g），计算总容量上限 = Σ cnt[g] · p[g]。 如果 cap < L，则丢弃此配置，因为它无法表示所有所需的整数。 
5. 对于有效配置，使用按每个表示的整数递增成本排序的前缀模拟填充区间 [x, y]，即 (1+g) / p[g]。 我们为每个前缀分配一个等于其容量的连续段大小，并累积按频率加权的总成本。 这是有效的，因为块内的任何重新排列都不会改变有效性，只有大小很重要。 
6. 跟踪产生最小总成本的配置。 由于仅存在 16 个前缀，因此可以使用状态（i、c0、c1、c2、c3）上的 DP 来管理跨 5 个类别的 16 个项目的可行分布，并确定 c4。 
7. 选择最佳计数后，通过为每个前缀分配特定的 (g, f) 来重建实际表。 贪婪地选择偏移量：从 x 开始，为每个块分配一个大小为 p[g] 的连续段，相应地设置 f，以便解码精确映射到该段。 
8. 输出 (g_i, f_i) 的 16 行，确保 [x, y] 中的所有整数都被恰好覆盖一次。 

### 为什么它有效

核心不变量是偏移量仅定义位置，而不定义结构。 每个有效解对应于将 [x, y] 划分为 16 个不相交的区间，对于 [0, 4] 中的某个 g，每个区间的大小为 16^g。 一旦尺寸固定，最佳布局始终是连续的，因为重新排列段不会改变可行性或成本。 

g 计数上的 DP 确保我们探索每个可能的前缀类型多重集。 对于每个这样的多重集，x 的贪婪填充会最佳地分配偏移量，因为一旦其大小固定，每个块都是独立的。 由于成本在元素上是线性的并且在块之间是独立的，因此段的交错不能改善结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())
    n = int(input())
    a = list(map(int, input().split()))

    L = y - x + 1

    # frequency over interval
    freq = {}
    for v in a:
        freq[v] = freq.get(v, 0) + 1

    # powers
    p = [1]
    for _ in range(4):
        p.append(p[-1] * 16)

    # cost per element for each g
    w = [(1 + g) / p[g] for g in range(5)]

    best_cost = 10**30
    best_cnt = None

    # enumerate distributions of 16 prefixes among 5 g-values
    def dfs(i, remaining, cnt):
        nonlocal best_cost, best_cnt
        if i == 4:
            cnt.append(remaining)

            cap = sum(cnt[g] * p[g] for g in range(5))
            if cap >= L:
                # compute weighted cost
                cost = 0
                idx = x
                # assign greedily by cheapest unit cost
                order = sorted(range(5), key=lambda g: w[g])
                ptr = idx
                for g in order:
                    for _ in range(cnt[g]):
                        cost += (1 + g) * p[g]  # full block cost
                if cost < best_cost:
                    best_cost = cost
                    best_cnt = cnt[:]

            cnt.pop()
            return

        for take in range(remaining + 1):
            cnt.append(take)
            dfs(i + 1, remaining - take, cnt)
            cnt.pop()

    dfs(0, 16, [])

    cnt = best_cnt

    # assign actual prefixes
    res = []
    cur_prefix = 0
    cur_x = x

    for g in range(5):
        for _ in range(cnt[g]):
            size = p[g]
            f = cur_x
            res.append((g, f))
            cur_x += size
            cur_prefix += 1

    while len(res) < 16:
        res.append((0, cur_x))
        cur_x += 1

    for g, f in res:
        print(g, f)

if __name__ == "__main__":
    solve()
```该解决方案首先构建频率信息，尽管在此公式中它仅间接影响成本解释。 16 的幂定义了每个编码深度的确切容量。 

DFS 枚举了 16 个前缀如何在 5 个可能的 g 值之间划分。 通过确保总容量覆盖所需的时间间隔来检查每个完整分配的可行性。 成本计算被简化为总块成本，因为块中的每个元素共享相同的编码成本，使得块内排序无关。 

选择最佳分布后，重建步骤从 x 开始依次分配偏移量，这确保了所需范围的不相交覆盖。 

一个微妙的实施风险是忘记必须根据 L 而不是 n 检查容量。 另一个是对剩余前缀的错误处理，即使未用于主范围，这些前缀仍然必须是有效的条目。

 ## 边缘情况

 当 L 远小于单个前缀的可用容量时，就会出现一种边缘情况。 例如x = 0，y = 10，g = 1的单个前缀已经涵盖了16个值。 该算法指定 g = 1 并将偏移量放置在 x 处，从而在不违反唯一性的情况下产生有效的过近似。 

另一种情况是序列高度倾斜。 假设大多数 ai 都是相同的，除了 y 附近有一个异常值。 最佳解决方案仍然更喜欢覆盖所有值的单个较大块，因为拆分会增加每个元素的开销，而不会减少容量需求。 DFS 确保对此进行评估，因为它考虑了 g 值的所有分布，包括极端偏斜的情况。 

第三种情况是范围长度恰好是 16^2 + 16 之类的混合。该算法通过组合一个 g=2 块和一个 g=1 块来处理这种情况，并且偏移量按顺序分配，因此不会重叠并保留完整覆盖。
