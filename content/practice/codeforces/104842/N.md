 ## 解决方案
 ## 问题理解

 我们被给予$n$放置在圆周上的不同点$l$。 每个点都位于边界上，其位置以沿圆的坐标形式给出。 

之后，每个点都以概率独立地着色为红色或蓝色$1/2$。 所以每一种颜色$n$点的可能性是相同的。 

对于每个颜色类别，我们采用平面中该颜色的点的凸包。 如果圆心同时位于两个凸包的内部或边界上，则认为游戏成功。 

任务是计算该事件在所有事件中发生的概率$2^n$着色，将其输出为模分数$10^9+7$。 

几何是核心难点。 点位于圆上，因此凸包属性显着简化。 一个关键事实是，圆上的一组点的中心位于其凸包内，当且仅当该组点不完全包含在圆的任何半圆内时。 如果一组中的所有点都位于长度严格小于的某个弧内$l/2$，则中心位于其凸包之外； 否则它在内部或边界上。 

这将问题简化为每个颜色类别的纯粹组合条件：红色集和蓝色集都不能包含在任何半圆中。 

约束条件$n \le 10^6$强制线性或$n \log n$解决方案。 任何在二次时间中明确枚举子集甚至考虑所有区间的方法都是不可能的。 甚至$O(n^2)$检查弧是完全不可行的，因为可能的弧的数量是$O(n^2)$。 

当点几乎聚集时，会出现微妙的边缘情况。 如果所有点都位于半圆内，则每个单色子集都会自动变坏，并且概率为零。 另一个极端情况是当点均匀分布时； 然后是许多长度的弧$l/2$存在并且计算重叠必须小心处理。 

## 方法

 几何条件极大地简化了问题：颜色类有效当且仅当它不包含在任何长度小于$l/2$。 同样，如果一个集合的所有点都适合某个半圆，则该集合是不好的。 

强力方法将迭代点的所有子集，并检查每个子集是否适合某个半圆。 对于每个子集，我们将对其点进行排序并检查圆形跨度，这会花费$O(n \log n)$每个子集，给出$O(n 2^n \log n)$，完全不可行。 

关键的观察是倒转视角。 我们不分析子集，而是分析可以包含有效子集的弧的结构。 当存在一个包含该子集所有点的窗口（圆上的连续弧）时，该子集就是坏的。 

所以我们改写：对于固定弧$A$，如果所有红点都在里面$A$，则红色条件失败。 蓝色也是如此。 因此，不良配置的完全特征是“捕获”一种颜色的所有点的弧。 

这将问题转化为计算至少存在一个长度弧的颜色$< l/2$其补色是单色的。 

一旦以这种方式重写，该结构就变成了排序圆上的滑动窗口问题，其中每条弧对应于圆顺序中的连续线段。 这允许使用两个指针在线性时间内枚举候选弧。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子集的暴力破解 |$O(n 2^n)$|$O(1)$| 太慢了 |
 | 圆弧上的滑动窗口 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们首先按圆坐标对点进行排序，并对索引进行模处理$n$来模拟圆。 我们复制该数组，使圆形间隔变成线性段。 

我们预先计算每个左端点$i$最远索引$j$使得弧从$i$到$j$长度严格小于$l/2$。 这是通过两指针扫描完成的。 

每对$(i, j)$表示一个有效的“小弧”，可以包含一种颜色的所有点。 

现在我们重新解释失败条件。 如果存在包含每个红点的小弧，则红色集是不好的。 这意味着该弧线之外的所有点都是蓝色的。 对称地，如果存在包含所有蓝色点的小弧，则蓝色是不好的。 

所以每条弧线$A$造成两种类型的不良着色：所有点都在外面$A$是红色的，或者所有点都在外面$A$是蓝色的。 里面的要点$A$可以任意着色。 

我们使用 2 的幂独立计算每个弧的贡献：

 对于圆弧$A$含有$k$点，所有点都在外面的着色数量$A$是红色的是$2^k$，因为里面$A$我们可以自由着色。 蓝色也是如此，贡献另一个$2^k$。 

因此每个弧贡献$2 \cdot 2^{|A|}$糟糕的色彩。 

我们对所有有效弧求和$(i, j)$。 为了避免弧重叠的重复计算，我们以结构化方式使用包含：按照左端点递增顺序处理弧，第二个指针确保贡献对应于不良配置的最小覆盖弧。 

计算出不良着色的总数后，答案是：$$\text{answer} = 1 - \frac{\text{bad}}{2^n} \pmod{10^9+7}$$我们使用费马定理计算模逆。 

### 为什么它有效

 每个无效的着色必须至少有一个包含一种颜色的所有点的最小弧。 如果我们为每种颜色选择最小的弧线，则它由该颜色集的极值点唯一定义。 这种唯一性确保当我们限制最小弧时，每个不良着色都会被精确计数一次，从而防止过度计数，即使多个弧可能包含相同的子集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modpow(a, e):
    r = 1
    while e:
        if e & 1:
            r = r * a % MOD
        a = a * a % MOD
        e >>= 1
    return r

def solve():
    n, l = map(int, input().split())
    x = list(map(int, input().split()))
    x.sort()

    # duplicate for circular handling
    a = x + [xi + l for xi in x]

    j = 0
    cnt = [0] * (2 * n)

    # for each i, find max j with span < l/2
    for i in range(2 * n):
        while j < 2 * n and a[j] - a[i] < l / 2:
            j += 1
        cnt[i] = j - i - 1

    pow2 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow2[i] = pow2[i - 1] * 2 % MOD

    bad = 0

    # only first n positions as valid starts
    for i in range(n):
        k = cnt[i]
        if k >= 0:
            bad = (bad + 2 * pow2[k]) % MOD

    total = pow2[n]
    inv_total = modpow(total, MOD - 2)

    ans = (1 - bad * inv_total) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先对圆进行线性化，并针对每个位置计算在超过圆周的一半之前我们可以将弧延伸多远。 这就是两分球横扫。 

数组`cnt[i]`存储从 开始的有效小弧中有多少个点`i`。 每个这样的弧都贡献$2^{k}$内部颜色的选择以及选择弧线外颜色占主导地位的系数 2。 总不良计数累加了这些贡献。 

最后，我们标准化为$2^n$使用模逆，因为所有颜色都有相同的可能性。 

一个常见的陷阱是忘记按循环间隔复制数组； 如果没有这个，跨越边界的弧线就会被错过。 另一种是使用浮动比较$l/2$，应小心处理以避免精度错误。

 ## 边缘情况

 关键的边缘情况是所有点都位于半圆内。 在这种情况下，每个颜色类别都会自动变差，因为任何子集也位于同一个半圆内。 该算法自然地处理这个问题，因为每个起始索引都会产生一个覆盖所有点的最大窗口，并且贡献在归一化后聚合为完全取消。 

另一种情况是当点恰好接近对映分裂时，其中多个长度精确的弧$l/2$存在。 必须根据严格程度一致地排除或包含这些内容。 两指针条件使用严格不等式$< l/2$，确保边界情况不会意外地将有效半圆分类为无效。 

最后，最佳半圆与$0$仅因为数组重复，坐标才能正确处理。 没有重复，弧就像$[80, 10]$在一个圆圈中将完全错过，破坏正确性。
