 ## 解决方案
 ## 问题理解

 我们在整数网格上得到两个点。 起点和目的地都严格远离坐标轴，这意味着任一端点的坐标都不为零。 这些点称为自由点。 网格还包含“昂贵”点，这些点正是位于轴上的点，其中 x 坐标或 y 坐标为零。 路径每次经过任意轴点，都会付出 1 的成本。 

任务是使用平面中的任何连续路径从起点移动到目的地，不限于网格边缘或直线段。 唯一重要的是路径至少接触多少个轴点一次。 目标是尽量减少这个数字。 

关键难点在于平面是连续的，因此路径可以任意弯曲。 然而，成本结构是离散的，仅取决于路径是否与 x 轴或 y 轴相交，以及以无法通过变形避免的方式相交多少次。 

坐标范围足够小，每次测试的任何 O(1) 推理就足够了。 对于数量级高达 10,000 的值，任何尝试模拟几何或离散化平面的解决方案都是不必要的，而且会显得矫枉过正。 正确的解决方案必须来自关于拓扑上必须交叉多少个轴的几何推理。 

一个天真的误解是假设每次路径穿过 x = 0 或 y = 0 时都会再次付出代价。 这会导致计数过多，因为在最佳配置中，精心选择的路径最多可以穿过每个轴一次。 

第二个常见错误是假设曼哈顿式推理，例如求和绝对坐标变化或考虑网格步骤。 这是不正确的，因为路径是连续的并且可以自由地跨越象限。 

打破幼稚想法的极端情况包括：

 起点和终点位于同一象限。 例如，(2, 3) 至(5, 7)。 天真的跨轴方法可能仍然认为您必须跨轴，但您可以完全留在同一象限中并且支付零费用。 

对角相对象限中的起点和终点，例如 (1, 1) 到 (-1, -1)。 这里两个坐标都改变了符号，迫使路径穿过两个轴，因此至少产生 2 成本。 

像 (1, 1) 到 (-1, 2) 这样的混合情况，只有 x 符号发生变化，因此只有一个轴交叉是不可避免的。 

真正的任务简化为推理坐标中的符号变化，以及是否可以通过通过单个象限布线来完全避免轴，或者是否在结构上强制交叉。 

## 方法

 蛮力的想法会尝试明确地考虑路径。 人们可以想象将平面离散成精细网格并运行最短路径搜索，其中穿过轴会增加成本。 这将正确地对问题进行建模，因为成本是在轴交叉点上累加的。 然而，该图是无限且连续的，任何足够精细以捕获所有有效行为的离散化都会导致大小爆炸。 即使限制为 20,000 x 20,000 的有界网格也会导致数亿个节点，使得 BFS 或 Dijkstra 不可行。 

关键的观察是，在这个问题中，飞机实际上并不复杂。 唯一有意义的结构是划分为由轴分隔的四个象限。 在象限内，运动是自由的。 唯一产生时间成本的是穿过 x = 0 或 y = 0 时。此外，在最优路径中每个轴最多只能穿过一次，因为重新穿过轴只会增加不必要的成本，而不会提高可达性。

这将问题简化为一个纯粹的组合问题，即起点和终点是否位于同一象限、共享一个坐标符号模式还是对角线相对。 如果两个坐标在两个端点具有相同的符号，则我们永远不需要穿过轴，因此成本为零。 如果恰好有一个坐标符号不同，则我们必须正好穿过一个轴。 如果两者不同，我们必须交叉两个轴，产生成本二。 

因此，几何学分解为符号比较。

 | --- | --- | --- | --- |
 | 暴力破解（网格搜索）| O(N²) 或更差 | O(N²) | 太慢了 |
 | 标志分析| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将每个点转换为一对符号，一个代表 x，一个代表 y。 每个符号告诉我们该点位于相应轴的哪一侧。 

1. 读取起点和终点的坐标。 我们实际需要的唯一信息是每个坐标是正还是负，因为输入中永远不会出现零。 
2. 判断x1 和x2 是否具有相同的符号。 如果它们不同，则从开始到结束的移动必须至少穿过 y 轴一次。 这是因为改变 x 的符号需要通过 x = 0。 
3. 判断y1和y2是否符号相同。 如果它们不同，则从开始到结束的移动必须至少穿过 x 轴一次，因为更改 y 的符号需要经过 y = 0。 
4. 计算这两个符号比较中有多少个不同。 该计数是所需的最小轴交叉数。 
5. 输出计数作为答案。 

该逻辑之所以有效，是因为每个轴都对应于一个拓扑屏障。 如果不穿过相应的轴，就不可能改变坐标上的符号，并且每个轴交叉都会产生一次成本。 

### 为什么它有效

 该平面被轴分为四个开放象限。 两点之间的任何连续路径必须在此分区空间中保持连续。 在象限之间移动正好对应于穿过其中一个轴。 由于成本仅在接触轴点时产生，因此最小成本恰好是分隔起始象限和结束象限的不同轴的数量。 没有路径可以减少这个数字，因为避免轴交叉意味着停留在不包含目的地的连接区域内。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def sign(x):
    return 1 if x > 0 else -1

def solve():
    x1, y1, x2, y2 = map(int, input().split())

    dx = sign(x1) != sign(x2)
    dy = sign(y1) != sign(y2)

    print(dx + dy)

if __name__ == "__main__":
    solve()
```该解决方案使用辅助函数将每个坐标减少为其符号。 由于保证不会出现零，因此我们只区分正值和负值。 

然后我们独立比较 x 坐标和 y 坐标的符号。 每一种不匹配都会导致一个不可避免的轴交叉。 最终的答案是这些不匹配的总和。 

该实现是恒定时间的并且避免任何几何模拟。

 ## 边缘情况

 一个微妙的情况是当两个点位于同一象限时。 例如，(10, 5) 至 (3, 7)。 该算法计算两个坐标的相同符号，从而导致零交叉。 路径可以完全在该象限内绘制，而无需接近任何一个轴，因此不会产生任何成本。 

另一种情况是只有一个坐标改变符号，例如 (5, 10) 变为 (-2, 8)。 x 符号不同，而 y 符号匹配。 该算法返回 1，对应于 y 轴的单个所需交叉点。 任何连续路径都必须在某个点经过 x = 0 才能翻转 x 符号。 

最后，当两个坐标都改变符号时，例如 (2, 3) 变为 (-4, -5)，则两个不匹配都会被计数。 路径必须以某种顺序穿过两个轴，并且任何变形都无法避免这两个交叉，因为起点和终点位于对角相对的象限。
