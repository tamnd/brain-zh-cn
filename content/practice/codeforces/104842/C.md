 ## 问题理解

 我们得到一个字节序列，每个字节都写为两位数的十六进制数，因此每个值的范围为 0 到 255。该序列表示原始内存转储，任务是确定该转储是否可以解释为有效的 C 风格字符串、有效的 Pascal 风格字符串，或者两者都解释。 

这里的 C 风格字符串是以稍微简化的方式定义的。 我们从头开始扫描字节数组。 我们可能会看到零个或多个“文本”字节，其中每个文本字节必须位于从 0x20 到 0x7f（含）的可打印 ASCII 范围内。 之后，必须有一个零字节来终止字符串。 这个零字节之后的所有内容都是不相关的垃圾，不会影响有效性。 

Pascal 风格的字符串以长度字节 l 开头。 接下来的 l 个字节必须全部位于从 0x20 到 0x7f（含）的可打印 ASCII 范围内。 在这 l 个字节之后，数组的其余部分是垃圾并被忽略。 长度 l 介于 0 到 255 之间，但它也必须适合实际数组大小，这意味着长度字节之后必须至少有 l 个字节。 

主要区别在于 C 字符串搜索终止零，而 Pascal 字符串在开头显式编码其长度。 

输入大小最多为 1000 字节，因此任何达到 O(n^2) 的解决方案都已经是安全的，但结构足够简单，线性扫描就足够了。 这强烈表明我们应该避免任何在不进行预处理的情况下尝试所有可能的分割点的暴力尝试。 

一些微妙的情况很重要。 

一个常见的错误是假设第一个零字节自动定义有效的 C 字符串。 这是不正确的，因为所有前面的字节都必须是可打印的。 例如，在输入中：```
01 00
```存在零，但前缀字节 01 不可打印，因此这不是有效的 C 字符串。 

对于 Pascal 字符串，另一个微妙的情况是长度字节超过剩余字节数。 例如：```
05 41 42
```这里l = 5，但是后面只有两个字节，所以即使它们是可打印的也是无效的。 

最后，l = 0 在 Pascal 字符串中有效，这意味着该字符串可能具有零内容字节并立即进入垃圾。 

## 方法

 蛮力方法将尝试每个可能的位置作为潜在的 C 终止符，并尝试每个可能的位置作为 Pascal 长度解释。 对于每个候选者，它将通过扫描数组的段来验证所需的约束。 在最坏的情况下，每次检查的成本为 O(n)，并且两种结构都有 O(n) 个选择，从而导致 O(n^2) 时间。 

关键的观察是这两种结构仅依赖于简单的前缀条件。 对于C字符串，我们只需要知道前缀是否只包含可打印字节。 对于 Pascal 字符串，我们只需要验证由第一个字节确定的单个固定段。 

这允许预处理一个布尔数组，该数组跟踪每个前缀是否完全可打印。 一旦可用，C 的有效性就会降低到检查零字节的位置。 帕斯卡有效性是直接的单一检查。

 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了 |
 | 最佳前缀检查 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将验证分为两项独立的检查，一项用于 C 风格解释，一项用于 Pascal 风格解释。 

### C 字符串检查

 1. 计算一个前缀数组，其中每个位置 i 表示从 0 到 i 的所有字节是否都在可打印范围内。 
2. 从左到右扫描数组并考虑字节为零的每个位置 i。 
3. 对于每个这样的位置 i，检查它之前的所有字节是否可以使用前缀数组打印。 
4. 如果至少存在一个这样的位置，则该数组可以被解释为有效的 C 字符串。 

原因是，有效的 C 字符串完全是通过选择第一个零出现的位置来确定的，并且前缀约束确保在其之前不会出现无效字节。 

### Pascal 字符串检查

 1. 将第一个字节读取为l，即候选长度。 
2. 检查l是否小于或等于n减1，确保有足够的剩余字节。 
3. 验证从索引 1 到索引 l 的所有字节是否都在可打印范围内。 
4. 如果两个条件都成立，则该数组是有效的 Pascal 字符串。 

这是可行的，因为 Pascal 编码从一开始就严格固定结构，因此一旦选择 l 就不会出现歧义。 

### 最终决定

 1. 组合两个布尔结果并输出四种情况之一：均有效、仅 C 有效、仅 Pascal 有效或均无效。 

### 为什么它有效

 正确性来自于以下事实：两种解释都施加了本地和基于前缀的约束。 C条件仅取决于是否有效终止
