 ## 解决方案
 ## 问题理解

 我们从顶部单元开始沿着帕斯卡三角形行走。 三角形中的每个位置都有一个等于二项式系数的值，并且从任何单元格，我们都可以移动到其六个相邻单元格之一：左上、右上、左、右、左下或右下，只要目的地位于三角形内。 我们必须生成一条简单的路径，永远不会重新访问单元格，始终从顶部单元格开始，最多访问 500 个单元格，并且所有访问过的单元格上的值之和等于给定数字$N$。 

关键的难点是每个细胞的重量不均匀。 前面的行具有较小的值，但较深的行包含较大的二项式系数，并且整个行具有为 2 的幂的结构化和。 这使得问题不再与几何有关，而更多地与构建一条“收集”精心选择的总重量块的路径有关。 

限制的范围很广$N$, 直至$10^9$，但路径长度以 500 为界。这立即排除了任何试图直接表示的方法$N$作为单个单元格值的总和贪婪地或探索网格。 相反，我们需要一种结构，其中每种结构选择都贡献大量可预测的量。 

出现微妙的边缘情况时$N$很小。 如果$N = 1$，路径只是起始单元格。 对于稍大的值，天真的尝试可能会尝试贪婪地向下移动，但这会失败，因为各个条目不是单调的，并且禁止重新访问结构。 另一个陷阱是假设我们可以独立地选择具有所需值的单元格，但邻接约束使路径连续并严重限制重新访问。 

唯一可行的策略是利用帕斯卡三角形的完整行具有非常干净的总和的事实，并设计一个可以完全消耗一行或最少地通过它的步行。 

## 方法

 暴力方法会尝试将其视为图形搜索，其中每个状态都是一个位置和一组访问过的单元格，累加总和直到我们精确到达$N$。 这很快就变得不可行。 即使采用积极的修剪，长度可达 500 的可能简单路径的数量也会呈指数增长，并且每条路径都需要对帕斯卡三角形的值进行求和。 这远远超出了任何合理的计算预算。 

关键的结构观察是帕斯卡的三角形行有一个强大的恒等式：行中值的总和$r$是$2^{r-1}$。 这意味着每一整行的行为就像伪装的二进制数字。 如果我们可以设计一个步行，要么完全遍历一行，要么以受控的方式跳过它，那么问题就相当于分解$N$化为二的幂。 

这会产生一个建设性的想法。 我们逐行向下移动，对于选定的行，我们以锯齿形模式遍历整行，以便每个单元格都被访问一次，并收集完整的行总和。 对于其他行，我们仅通过单个边界单元，贡献最小的受控量。 通过选择要完全遍历的行，我们可以编码$N$以二进制形式。 

剩下的挑战是维护有效的简单路径。 这是通过改变每行的方向来处理的，这样我们就不需要跳转或重新访问单元格。

 ## 算法演练

 我们利用二进制分解$N$，其中每一位决定我们是完全遍历一行还是仅通过它。 

1. 从位置开始$(1,1)$。 这提供了一个固定的初始值 1，它对应于帕斯卡三角形的第一行。 
2. 维护交替每行的当前方向标志。 这确保我们可以蜿蜒穿过一行，而无需重新访问单元格，同时保持与下一行的连接。 
3.对于每行索引$r$从2开始，根据位表示来决定$N$。 如果$(r-2)$第 位$N$设置完毕后，我们完全遍历行$r$从左到右或从右到左取决于方向。 这正是贡献$2^{r-1}$到总和。 
4. 如果未设置该位，则我们从当前行的边界直接沿边缘移动到下一行，仅访问该行中的一个新单元格。 这使得路径变得简单，并确保我们不会意外地积累额外的重量。 
5. 继续，直到所选行的累计贡献达到$N$。 因为$N \le 10^9$，完整贡献只需要大约 30 行，路径的其余部分是线性遍历，将总长度保持在 500 以内。 
6、按顺序输出访问过的坐标序列。 

### 为什么它有效

 每个完全遍历的行都准确贡献$2^{r-1}$，并且每个这样的行在贡献方面都是独立于其他行的。 路径构造保证我们永远不会重新访问单元格，因为每一行都是在一次单调扫描中遍历的。 其余部分移动仅接触边界单元，因此它们不会干扰二进制编码结构。 这使得总和恰好等于所选的行幂子集，对应于二进制表示$N$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n):
    path = []
    r = 1
    k = 1
    path.append((r, k))

    remaining = n
    direction = 1  # 1 means moving right, 0 means moving left

    # We process rows until remaining becomes 0
    # We decide whether to take full row r or not based on bits of remaining
    for r in range(1, 31):
        if remaining == 0:
            break

        # If we are at row 1, we already included (1,1)
        if r == 1:
            continue

        bit = remaining & 1
        remaining >>= 1

        if bit == 1:
            # traverse full row r
            if direction == 1:
                for c in range(1, r + 1):
                    path.append((r, c))
            else:
                for c in range(r, 0, -1):
                    path.append((r, c))
        else:
            # move only along the edge
            if direction == 1:
                path.append((r, 1))
            else:
                path.append((r, r))

        direction ^= 1

    return path

def solve():
    t = int(input())
    for tc in range(1, t + 1):
        n = int(input())
        path = solve_case(n)

        print(f"Case #{tc}:")
        for r, k in path:
            print(r, k)

if __name__ == "__main__":
    solve()
```该解决方案逐行构建路径。 变量`remaining`跟踪有多少二进制分解仍未分配。 每次迭代消耗一位并决定相应的行是完全遍历还是仅触及其边界。 这`direction`变量确保当我们完全遍历一行时，我们以直线单调扫描方式移动，这避免了重新访问单元格并保持邻接有效。 

一个常见的错误是忘记整行遍历必须是连续的。 在端点之间跳转会违反邻接规则，因此代码显式地按顺序遍历每一列。

### 示例 2：N = 5

 二进制表示为 101，因此我们完整地取第 1 行和第 3 行。 

| 步骤| 行| 行动| 路径添加 | 剩余|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 开始| (1,1) | 5 |
 | 2 | 2 | 跳行| (2,1) | 2 |
 | 3 | 3 | 全排| (3,1),(3,2),(3,3) | (3,1),(3,2),(3,3) | 0 |

 这展示了跳跃和完全遍历如何结合起来。 第 1 行贡献 1，第 3 行贡献 4，总和为 5。

 ## 边缘情况

 对于$N = 1$，算法永远不会进入初始化之外的行遍历逻辑。 输出只是起始单元格，它已经完全满足总和要求。 

对于二的幂，例如$N = 1024$，二元分解选择单个深行。 该算法仅执行一行的完全遍历并跳过所有其他行，从而生成一条长但有效的单调之字形路径。 这永远不会违反 500 的限制，因为只需要大约 10 行。 

对于交替位数，例如$N = 170$，构造在全行遍历和边界步骤之间交替。 方向翻转保证了这些交替决策之间的连续性，防止重访并在整个步行过程中保持邻接。
