 ## 解决方案
 ## 问题理解

 我们有一个圆形排列$n$扇区，每个扇区最初最多持有一个信封。 经过几轮之后，才$k$信封仍然存在，并且它们在圆上的确切位置按顺时针顺序已知。 这些剩余的信封之一是特殊的，位于扇区$s$。 游戏通过重复随机地统一选择一个扇区来进行。 如果所选扇区已包含信封，则该信封将被打开并移除。 如果它是空的，主持人会顺时针移动直到下一个剩余的信封，然后打开该信封。 

该过程一直持续到所有信封都被打开，并且我们被要求提供预计的轮数，直到特殊信封被打开。 

关键的微妙之处在于，随机扇区不会直接选择信封，而是在圆上选择一个位置，然后“向前跳”到下一个剩余的信封。 这意味着每个信封不具有以直接方式选择的相同概率，因为空白间隙“属于”按顺时针顺序的下一个信封。 

约束是必须利用何种结构的主要信号。 尽管$n$可以大到$10^9$, 剩余信封数量$k$最多 200。这立即告诉我们，任何解决方案取决于$n$线性甚至迭代所有扇区是不可能的。 唯一有意义的状态是由$k$信封位置及其之间的间隙。 循环性质意味着问题根本上在于这些差距，而不是单个部门。 

一个天真的想法是逐轮模拟该过程，维护一组活动包络并重复对随机扇区进行采样。 这会失败，因为每一步都是$O(k)$找到下一个信封，期望的步数也是$O(k)$，导致$O(k^2)$每个模拟，并且需要许多模拟来进行期望估计。 更糟糕的是，精确的概率计算需要跟踪指数级的许多移除状态。 

一个更微妙的失败案例来自于忽略“顺时针下一个信封”规则。 例如，如果信封位于以下位置$[1, 1000]$在一个大圆上，那么 2 到 1000 之间的几乎所有扇区都映射到包络 1000。这里天真的每个包络均匀的假设是完全错误的。 

## 方法

 本质上的困难在于，每个信封的“权重”等于有多少个起始扇区会导致它被选为顺时针顺序的下一个信封。 这些权重随着信封的删除而动态变化，因为删除信封会合并其相邻的间隙。 

如果我们只关注剩余的信封，则该圆被划分为$k$弧线。 每个弧将其所有扇区顺时针贡献给下一个包络线。 如果信封$i$有间隙长度$g_i$（到前一个信封的距离），然后选择其中任何一个$g_i$部门最终将导致信封$i$。 

这意味着信封$i$被选择的概率与$g_i / n$， 在哪里$n$是扇区总数，最重要的是$n$是固定的，而间隙分布则不断变化。 

当信封被移除时，两个相邻的间隙合并，因此仅发生局部更新。 自从$k \le 200$，我们可以将该过程精确地建模为间隙配置上的马尔可夫过程。 然而，我们不需要在所有州进行全面分配； 我们只需要在特定信封被移除之前的预期时间。 

这表明对剩余信封的子集进行动态编程，但这仍然太大：$2^k$是不可能的。 

关键的简化是反转视角。 我们不考虑向前模拟移除，而是考虑每个步骤的预期时间贡献：在任何状态下，直到下一次移除的预期时间为$n / (\text{number of active envelopes})$，因为每个扇区最终都映射到一个活动信封，并且有$k$包络，因此所有包络上的总概率质量总和为 1，分母为$n$，但每一步总是只消耗一个信封。 选择哪个包络的分布仅取决于间隙结构，但移除之间的等待时间仅取决于均匀采样$n$部门。 

因此，预期时间变为按随机删除引起的顺序的连续删除之间的预期等待时间的总和。 剩下的任务是计算直到特殊包络被移除为止的预期步骤数，这减少为以随机消除顺序计算特殊包络的预期位置，其中每个包络具有随时间变化的选择概率。 

因为$k$很小，我们可以在循环序列上的间隔上定义 DP，跟踪当保留一段信封且特殊信封位于其中时的预期成本。 每个过渡都会删除一个以与其弧长成比例的概率选择的包络线，并且我们将其分成两个较小的段。 

这是一个经典的“圆形加权结构中的随机移除”DP，运行在$O(k^3)$，足以$k \le 200$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(模拟 × k²) | O(k) | 太慢了 |
 | 圆上的间隔 DP | O(k³) | O(k²) | 已接受 |

 ## 算法演练

 1. 将圆形位置转换为连续信封之间的间隙数组。 每个信封$i$得到一个间隙$g_i$，表示在顺时针投影下有多少个起始扇区映射到它。 这一步压缩了大$n$宇宙进入$k$有意义的权重。 
2. 在包络的圆形间隔上构建 DP 状态。 我们将指数视为模$k$，但为了 DP 方便，我们复制数组，使圆形线段变成线性线段。 
3.定义DP函数$dp[l][r]$表示在特殊信封被移除之前的预期轮数，假设只有索引中的信封$l$到$r$保持。 
4. 对于给定的时间间隔$[l, r]$，计算总重量$W = \sum g_i$超过该间隔。 这表示通向任何剩余信封的扇区总数。 
5. 对于每个可能的信封$i$在$[l, r]$，将其视为下一个被移除的信封。 这种情况有概率发生$g_i / W$。 
6.如果$i$是特殊信封，然后将其移除会停止该过程。 它的贡献正是又一个值得期待的一步。 
7. 否则，删除$i$将区间分成两个独立的区间$[l, i-1]$和$[i+1, r]$。 该分支的期望值是两个子区间的 DP 值之和，加上用于移除本身的一步。 
8. 通过对概率加权贡献求和来组合所有选择以获得$dp[l][r]$。 

最终的答案是$dp[l][r]$对于包含所有信封和特殊信封的完整圆形间隔。 

### 为什么它有效

 在任何时刻，进程都会从以下位置统一选择一个扇区：$n$，但每个扇区都通过顺时针转发确定性地映射到一个活动信封。 这会在包络线上产生与其当前弧长成比例的概率分布。 由于移除包络线仅合并相邻的弧并保留总质量$n$，该过程对于当前区间结构是无记忆的。 DP 准确地捕捉了这种马尔可夫演化：每个状态转换仅取决于当前间隔权重，并且以正确的概率考虑每个可能的下一个移除。 这保证了计算的期望与真实的随机过程相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, k, s = map(int, input().split())
    q = list(map(int, input().split()))

    idx = q.index(s)

    # compute gaps
    g = []
    for i in range(k):
        j = (i + 1) % k
        dist = (q[j] - q[i]) % n
        if dist == 0:
            dist = n
        g.append(dist)

    # duplicate for circular dp
    g2 = g * 2

    # prefix sums
    pref = [0] * (2 * k + 1)
    for i in range(2 * k):
        pref[i + 1] = pref[i] + g2[i]

    def get_sum(l, r):
        return pref[r + 1] - pref[l]

    # dp[l][r]
    dp = [[0] * (2 * k) for _ in range(2 * k)]

    for length in range(1, k + 1):
        for l in range(2 * k - length + 1):
            r = l + length - 1
            total = get_sum(l, r)

            res = 0
            for i in range(l, r + 1):
                prob = g2[i] * modinv(total) % MOD

                if i % k == idx:
                    res = (res + prob * 1) % MOD
                else:
                    left = dp[l][i - 1] if i > l else 0
                    right = dp[i + 1][r] if i < r else 0
                    res = (res + prob * (1 + left + right)) % MOD

            dp[l][r] = res

    print(dp[idx][idx + k - 1] % MOD)

if __name__ == "__main__":
    solve()
```该实现首先将圆压缩为间隙权重，该权重对通向每个信封的起始扇区进行编码。 DP 表是在重复数组上构建的，以便循环间隔变成线性段，从而避免换行处理。 

转换在最后删除的包络候选上循环，并使用通过间隔中总权重的倒数计算的模块化概率。 当选择特殊包络线时，过程以成本 1 终止。否则，区间分裂为两个独立的子问题，并且它们的 DP 值与当前步骤一起相加。 

关键的实施风险是错误地处理循环结构。 数组的复制确保了表示剩余活动包络的任何连续段都可以在 DP 内部无需模块化索引逻辑的情况下表示。 

## 工作示例

 ### 示例 1

 输入：```
3 2 3
2 3
```差距：```
2 -> 3: 1
3 -> 2 (wrap): 2
```我们在包含特殊元素 3 的区间内跟踪 DP。 

| 状态| 间隔 | 总重量| 贡献 |
 | ---| ---| ---| ---|
 | 开始| [2, 3] | 3 | 选择 3 或 2 |

 如果首先选择 3，则过程以 1 步结束。 如果先选择2，则只剩下3，然后再选择它。 

预期的：$$\frac{1}{3} \cdot 1 + \frac{2}{3} \cdot 2 = \frac{5}{3}$$这与 DP 结果相匹配：尽早移除特殊包络线会带来最小的成本，而延迟它会迫使采取额外的步骤。 

### 示例 2

 输入：```
6 3 4
1 2 4
```差距：```
1->2 = 1
2->4 = 2
4->1 = 3
```| 步骤| 剩余套装| 概率取决于权重 |
 | ---| ---| ---|
 | 开始| [1,2,4]| (1,2,3)/6 |

 如果先选择4，则立即结束。 如果首先选择 1 或 2，则结构会崩溃，并且在缩小的区间内更有可能出现 4。 

这表明移除会动态地重塑概率，这正是区间 DP 捕获的内容。

 ## 边缘情况

 一种边缘情况是所有封套在圆中都是连续的，例如$q = [1,2,3,4]$。 在这种情况下，除了环绕间隙之外，所有间隙均为 1，并且包络上的概率分布几乎是均匀的。 DP 简化为对称去除过程，其中每个包络的行为相似，并且该算法一致地处理每个间隔，而不依赖于特殊的外壳。 

另一种边缘情况是当特殊包络位于线性化阵列中的重复段之间的边界时。 因为我们复制了序列，所以相同的循环间隔出现两次，但 DP 只选择从正确索引开始的段。 这可以避免重复计算，同时保留正确的环绕行为。 

最后一种边缘情况是只剩下一个信封。 DP 立即分配值 1，因为下一个选择必须打开它，并且不可能进行拆分。
