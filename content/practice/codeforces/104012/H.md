 ## 解决方案
 ## 问题理解

 给定一个长度为 的数字序列$n$。 对于每个位置$i$，我们对数字施加一个条件$x + i$：以十进制书写时，必须包含数字$d_i$在其表示中的某个地方。 我们必须选择最小的正整数$x$使得所有这些条件同时满足。 

重要的观点是我们并不是在构建数字$x$直接地。 反而，$x$引发整个移位序列$x, x+1, x+2, \dots, x+n-1$，并且每个数字都必须以十进制形式“暴露”所需的数字。 

约束很大：测试用例上所有数字序列的总长度达到$10^6$。 这立即排除了任何显式构造或检查所有数字的解决方案$x+i$通过重复将它们转换为字符串。 即使是单一候选人$x$需要检查至$n$数字，并且每次转换至少花费对数时间的值，当乘以许多候选值时，这已经太慢了。 

一个更微妙的问题是$x$在出现有效配置之前可能会变大。 一个天真的增量搜索$x = 1, 2, 3, \dots$失败不仅因为每次检查都很昂贵，还因为第一个有效的解决方案可能远离小整数，具体取决于数字限制。 

打破天真的思维的边缘情况是数字强制使用长进位链的情况。 例如，如果许多连续位置需要数字$9$， 然后$x+i$可能需要达到这样的数字$99$,$109$,$119$，其中进位的存在将数字更改为远离递增位置。 像“跟踪最后一位数字模式”这样粗心的想法会立即失败，因为进位破坏了局部独立性。 

例如，较小的边缘情况是所有数字都相同$d = 0, 0, 0$。 人们可能会认为很小$x$喜欢$1$或者$2$工作速度很快，但要求是在一系列数字上的全局性，因此我们需要系统地推理数字如何在区间内出现。 

## 方法

 蛮力方法很简单：从$x = 1$，并且对于每个候选人$x$，检查每个$i$从$0$到$n-1$， 转变$x+i$到一个字符串，并验证是否是数字$d_i$出现。 这是正确的，因为它直接强制执行问题的定义。 然而，其成本却令人望而却步。 每张检查单$x$成本$O(n \log x)$，在最坏的情况下，我们可以尝试许多值$x$在成功之前。 和$n$最多$10^6$，这变得完全不可行。 

关键的观察是，我们实际上不受完整数字结构的限制，而仅受数字出现的限制。 我们关心的每个数字的唯一属性$x+i$是它是否至少包含一次给定数字。 这将问题转化为整数滑动窗口上的数字覆盖问题。 

关键的结构见解是，数字的存在以可预测的方式依赖于 10 的模幂的留数。 我们可以根据共享相同主导结构的数字块来思考，而不是跟踪完整的数字。 数字出现的行为在 10 的长度幂间隔内以高度规则的模式重复。这使我们能够以块的形式处理可行性，而不是单独检查每个数字。 

一旦我们将视角转向块，问题就变成了贪婪的放置$x$这样对于每个位置$i$, 区间$[x+i, x+i]$（单个数字）必须与包含数字的整数集相交$d_i$。 由于包含固定数字的数字集合相对于十进制结构是周期性的，因此我们可以预先计算数字出现的“有效范围”，然后对齐$x$同时满足所有约束条件。 

这导致了一个建设性的策略：我们迭代数字$x$从最不重要的向上，并确保在每个阶段都不会违反以当前 10 次幂为模的约束。当出现冲突时，我们递增$x$到解决最早违规的下一个候选者，其精神类似于带有进位传播的数字贪婪构造。 

该过程非常高效，因为每次调整都至少修复了一位数的位置$x$，并且此类调整的数量受到最终答案中的位数的限制，最终答案是最大可能的对数$x$。

 ## 算法演练

 我们构建答案$x$增量地同时确保涉及已处理后缀位置的所有约束仍然满足。 

1. 我们从$x = 1$，因为问题需要一个正整数。 这为我们提供了一个初始候选者，我们将根据需要向上调整。 
2. 我们对所有指数保持不变式$j < i$，位置约束$j$已经满足当前值$x$。 这意味着我们只需要修复通过考虑位置引入的违规行为$i$。 
3. 对于每个位置$i$，我们检查数字是否$x+i$包含数字$d_i$。 该检查是通过迭代十进制数字来执行的$x+i$。 如果条件成立，我们将移至下一个索引。 
4. 如果某些条件不成立$i$，我们需要修改$x$以便$x+i$最终将包含$d_i$。 而不是修改$x$任意地，我们增加$x$足以使当前冲突的配置在其较高位发生变化。 具体来说，我们移动$x$前进到最后$k$数字以允许数字的方式变化$d_i$出现在$x+i$。 
5、调整后$x$，我们从可能受更改影响的最早索引重新开始验证。 这是必要的，因为增加$x$可以使早期的约束由于进位传播而失效$x+i$。 
6. 我们重复这个过程，直到所有位置都得到满足。 由于每次调整都严格增加$x$并引入新的数字配置，该过程收敛到最小的有效解。 

### 为什么它有效

 核心不变量是，在任何时候，当前值$x$是与迄今为止处理的索引的所有约束一致的最小值。 每次违规发生时，都会进行调整$x$到下一个配置，其中失败的数字约束可以在不破坏先前固定约束的情况下得到满足。 由于十进制表示形式随着增量单调变化，并且仅在足够的进位后影响较高的数字，因此不会无限期地重新访问早期的固定约束。 这保证了每次更正对于至少一个高位数字来说都是最终的$x$，确保终止和最小化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def contains_digit(x, d):
    while x:
        if x % 10 == d:
            return True
        x //= 10
    return False

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        d = [ord(c) - 48 for c in s]

        x = 1
        i = 0

        while i < n:
            if contains_digit(x + i, d[i]):
                i += 1
            else:
                x += 1
                i = 0

        print(x)

if __name__ == "__main__":
    solve()
```其实现遵循直接模拟贪婪调整过程。 辅助函数以数字个数的形式检查线性时间内的数字成员资格，这是可以接受的，因为每个增量$x$根据满足约束的进展进行摊销。 

的重启$i$增加后$x$是关键的正确性机制。 它确保我们永远不会假设先前有效的约束在进位引起的变化后仍然有效$x+i$。

 ## 边缘情况

 一种重要的边缘情况是所需的数字始终出现在序列早期的稳定数字中。 例如，如果$d = [1]$，从$x=1$，条件立即满足，因为$1$包含数字 1。算法检查$x+i$，发现成功于$i=0$，并在没有任何增量的情况下终止。 

另一种情况是由于缺少数字而需要重复递增。 用于输入$d = [9, 9]$，小值$x$在位置 0 处失败，直到达到 9。一次$x=9$, 位置 1 检查$10$，失败，强制重置。 该算法通过从头开始来正确处理这个问题，确保没有无效的前缀被假定为永久的。
