 ## 解决方案
 ## 问题理解

 我们得到了一组多张卡片，其中每张卡片的值都在 0 到 n − 1 之间。在任何时刻，我们都知道每个值存在多少个副本。 我们可以将所有卡片划分为任意数量的非空组。 对于每个组，我们计算其 mex，即未出现在该组中的最小非负整数。 分区的分数是所有组的 mex 值的总和，我们希望最大化该分数。 

初始配置后，多重集会通过插入或删除单个卡值的点更新随时间发生变化。 每次更新后，我们必须重新计算可能的最大分数。 

关键难点是分区不固定。 我们没有被要求构建它，只是为了计算可实现的最佳 mex 值总和。 

约束很大：n 和更新次数 q 都达到大约 2 × 10^5，并且每个操作改变单个频率。 这立即排除了每次更新时从头开始重新计算答案的任何解决方案，因为即使是 O(n) 重新计算，在最坏的情况下也会导致大约 4 × 10^10 次操作。 我们需要一个能够在每次更新的大致对数时间内维护答案的结构。 

如果每次更新后试图在本地贪婪地形成一堆，就会出现微妙的失败情况。 例如，如果我们总是尝试“扩展”现有的桩，我们很快就会遇到非本地依赖关系：添加一个额外的 0 可以同时增加许多不同桩的 mex，即使是那些不明显共享结构的桩。 这使得贪婪构造在更新下不稳定。 

另一个常见的错误是假设答案仅取决于我们可以形成的完整“0 到 k”链的总数。 这种直觉很接近但不完整，因为较高值的贡献取决于前缀约束如何同时在所有值上传播。 

## 方法

 我们首先以更具结构性的方式重新表述优化。 我们不再考虑堆，而是翻转视角：堆为每个整数 x 的最终总和贡献 1，使得其 mex 至少为 x + 1。当堆包含从 0 到 x 的每个值时，就会发生这种情况。 

因此，具有 mex M 的每一堆都对答案贡献 M，并且对低于 M 的每个前缀阈值贡献 1。 

现在确定阈值x。 我们询问有多少堆的 mex 可以大于 x，这意味着它们必须包含 0 到 x 的所有值。 每个这样的堆都需要该前缀中每个值的至少一个副本。 因此，此类堆的最大数量受到该前缀中最稀有值的限制，即 a[0]、a[1]、...、a[x] 中的最小频率。 

如果我们定义 b[x] = min(a[0..x])，那么 b[x] 正是 mex 严格大于 x 的最大桩数。 对所有阈值的贡献求和得出的答案是所有 x 上的这些前缀最小值的总和。 

因此，整个问题简化为在点更新下维护数组的前缀最小值之和。 

强力解决方案将在每次更新后重新计算前缀最小值 O(n)，给出 O(nq)，这在最大约束下太慢。 

关键的观察是前缀最小值形成一个非递增序列。 当单个位置发生变化时，前缀最小序列仅从该索引开始变化，并且变化具有非常结构化的形状：它变成运行最小值的重新计算，这是单调的。 

这种结构允许我们维护存储该段的整个前缀最小序列的段，并以尊重左段最小值剪切的方式合并它们。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每次更新后重新计算 | O(nq) | O(n) | 太慢了|
 | 最小前缀序列上的分段结构 | O(q log n) 摊销 | O(n log n) | O(n log n) | 已接受 |

 ## 算法演练

 ###核心理念

 我们维护数组 a，并在概念上定义派生数组 b，其中 b[i] 是 a[0..i] 中的最小值。 答案是所有 b[i] 的总和。 

我们维护一个段树，其中每个节点存储其段的完整前缀最小行为，而不是在每次更新后显式重建 b。 

### 1. 段的表示

 对于数组的每个段，我们将其前缀最小序列的压缩表示存储为对列表。 每对代表一个值以及前缀最小数组中有多少个连续位置具有该值。 

这是有效的，因为前缀最小值只会减少，不会增加，因此序列自然是分段常数。 

我们还将最小值存储在段中，这是组合段时需要的。 

### 2.叶子初始化

 对于单个位置 i，前缀最小序列只是一个值，a[i]。 所以叶子节点存储了一个包含(a[i], 1)的段，其和等于a[i]。 

### 3. 合并两个段

 当组合左段 L 和右段 R 时，我们首先将 L 中的所有前缀最小值保持不变，因为 L 中的所有前缀都在 R 之前。 

对于 R，我们必须考虑到 R 内的任何前缀最小值都不能超过 L 中的最小值这一事实。这个最小值就像一个全局上限，可以减少 R 的前缀最小值序列中的所有值。 

因此，我们从概念上讲，采用 R 的存储序列，并将大于 L 的最小值的每个值替换为该最小值。 经过这次裁剪，R仍然是一个有效的非增序列，如果需要的话我们将它合并到L的尾部。 

这种合并产生用于串联的前缀最小序列。 

### 4.答案提取

 在线段树的根部，我们简单地将其存储的最小前缀序列中的所有值相加。 这个总和等于所需的答案。 

### 为什么它有效

 不变的是，每个节点在限制于该段的定义 b[i] = min(a[0..i]) 下精确存储其段的前缀最小序列，并且该序列始终保持压缩单调形式。 合并操作保留了正确性，因为串联的前缀最小值仅取决于左段的前缀最小值，左段充当右段的统一上限。 由于前缀最小值是单调的，因此裁剪不会引入不一致，只会合并相等的值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("mn", "seq", "sum")
    def __init__(self, mn=10**18, seq=None, s=0):
        self.mn = mn
        self.seq = seq if seq is not None else []
        self.sum = s

def merge(L: Node, R: Node) -> Node:
    if not L.seq:
        return R
    if not R.seq:
        return L

    res = Node()
    res.mn = min(L.mn, R.mn)

    seq = []

    for v, c in L.seq:
        seq.append([v, c])

    cap = L.mn
    for v, c in R.seq:
        nv = min(v, cap)
        if seq and seq[-1][0] == nv:
            seq[-1][1] += c
        else:
            seq.append([nv, c])

    res.seq = [(v, c) for v, c in seq]
    res.sum = sum(v * c for v, c in res.seq)
    res.mn = min(L.mn, R.mn)
    return res

def build(a, v, l, r):
    if l == r:
        node = Node(a[l], [(a[l], 1)], a[l])
        v[l + size] = node
        return
    m = (l + r) // 2
    build(a, v, l, m)
    build(a, v, m + 1, r)
    v.append(merge(v[l + size], v[m + 1 + size]))

def update(v, idx, val):
    i = idx + size
    v[i] = Node(val, [(val, 1)], val)
    i //= 2
    while i:
        v[i] = merge(v[2 * i], v[2 * i + 1])
        i //= 2

def query(v):
    return v[1].sum

n = int(input())
a = list(map(int, input().split()))
q = int(input())

size = 1
while size < n:
    size *= 2

seg = [Node() for _ in range(2 * size)]

for i in range(n):
    seg[size + i] = Node(a[i], [(a[i], 1)], a[i])

for i in range(size - 1, 0, -1):
    seg[i] = merge(seg[2 * i], seg[2 * i + 1])

out = []
out.append(str(seg[1].sum))

for _ in range(q):
    p, v = map(int, input().split())
    if p == 1:
        a[v] += 1
    else:
        a[v] -= 1

    i = v + size
    seg[i] = Node(a[v], [(a[v], 1)], a[v])

    i //= 2
    while i:
        seg[i] = merge(seg[2 * i], seg[2 * i + 1])
        i //= 2

    out.append(str(seg[1].sum))

print("\n".join(out))
```该实现使用自下而上的线段树。 每个节点将压缩的最小前缀序列存储为值块列表以及该序列的总和。 更新修改单个叶子并使用合并操作重新计算祖先。 

一个关键细节是所有更改都是本地的：单个增量或减量仅影响一个叶子，并且所有更高的节点都在 O(log n) 合并中重建。 

正确性取决于维护每个节点表示其段的前缀最小序列而不是原始数组值的不变性。 

## 工作示例

 考虑一个小数组 a = [2, 1, 3]。 

我们构建前缀最小值：b = [2, 1, 1]，所以答案是 4。 

| 步骤| 数组 | 前缀最小值 b | 总和 |
 | --- | --- | --- | --- |
 | 初始化| [2,1,3]| [2,1,1]| 4 |

 现在将 0 添加到索引 1，得到 a = [2,2,3]。 前缀最小值变为 [2,2,2]，总和为 6。 

| 步骤| 数组 | 前缀最小值 b | 总和 |
 | --- | --- | --- | --- |
 | 更新 | [2,2,3]| [2,2,2]| 6 |

 这显示了单个更改如何传播到所有后续前缀位置。 

跟踪确认更新不仅影响本地值，还可以展平或重塑整个后缀行为，这就是需要段级维护的原因。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(q log n) 摊销 | 每次更新都会重建 O(log n) 个节点，每次合并在压缩段大小方面都是线性的 |
 | 空间| O(n log n) | O(n log n) | 每个线段树节点都存储一个压缩的最小前缀表示 |

 复杂度完全符合 n 和 q 高达 2 × 10^5 的限制，因为每个操作仅涉及对数数量的节点，并且每个节点存储紧凑的单调数据。

 ## 边缘情况

 一个关键的边缘情况是所有值都为零。 在这种情况下，每个前缀最小值保持为零，因此无论更新如何，答案始终为零。 段结构干净地处理了这个问题，因为所有节点序列都会折叠成单个重复值，并且合并不会改变任何内容。 

另一个边缘情况是单个位置成为新的全局最小值。 例如，如果一个元素减少到零，它会强制其后面的每个前缀最小值也下降。 线段树在合并期间通过裁剪步骤处理此问题，确保所有受影响的后缀节点正确反映新的全局边界。 

第三种情况是在同一索引处重复切换。 由于每次更新都会完全覆盖叶子并重新计算其祖先，因此重复更新不会累积错误。 树总是沿着受影响的路径从头开始重建精确的前缀最小结构。
