 ## 解决方案
 ## 问题理解

 我们给定了一个上限$n$，我们考虑所有有序对$(x, y)$其中两个值都介于 1 和$n$。 对于每一对这样的对，我们运行欧几里得算法的修改版本。 根纳迪没有用余数替换较大的数字，而是错误地替换了$x$与整数商$x \div y$，然后交换两个变量，并在第二个值保持正值时重复此操作。 

该过程要么在有限数量的步骤中终止，要么因未能正确减少状态而变得无效。 在所有对中$(x, y)$，我们只对过程实际完成的那些感兴趣，并且当它完成时，返回的值与原始对的真正最大公约数相匹配。 

所有有效对均按字典顺序列出$x$， 然后$y$，并且我们必须回答询问$p_i$-th 这样的对或报告它不存在。 

约束条件很大，有$n, q \le 2 \cdot 10^5$，直到$2 \cdot 10^5$查询。 对每一对进行简单的检查是不可能的，因为网格包含$n^2$候选人，已经达到$4 \cdot 10^{10}$在最坏的情况下。 

第二个隐藏的困难是模拟单个对的算法也不是恒定时间。 每个步骤都执行除法和交换，并且步骤的数量会随着数字的大小而增加，因此即使测试几百万对也变得不可行。 

出现微妙的边缘情况时$y = 1$。 变换立即设置$x = x \div 1 = x$，因此交换不会减少状态。 除非小心处理，否则循环永远不会终止。 在正确的对枚举中，仍然必须正确考虑此类情况，因为它们代表过程的有效固定点。 

## 方法

 蛮力的想法很简单：迭代所有对$(x, y)$，模拟有bug的欧氏过程，检查是否终止以及最终结果是否等于$\gcd(x, y)$。 这在概念上是正确的，因为它直接符合有效性的定义。 然而，它太慢了，因为有$O(n^2)$配对，每次模拟最多需要$O(\log n)$或者更糟，取决于国家如何演变。 这导致最坏情况的复杂性远远超出可接受的限度。 

关键的观察结果是，转变$(x, y) \rightarrow (y, x \div y)$具有较强的结构性约束。 一次$y > x$，商立即变为零，系统以可预测的方式崩溃。 该过程正确运行并干净地终止的唯一方法是除法序列反映欧几里得算法的受控形式，其中所有中间商的行为就像连分式展开中的数字一样，不会破坏该过程的稳定性。 

这导致了一个关键的简化：有效对与过程在少量步骤中稳定的那些对完全对应，并且可以通过构造从逆转换下的基本情况可到达的所有状态来系统地生成这些对。 我们不是检查对，而是生成它们。 

逆向观点才是真正的转变。 而不是从开始$(x, y)$并继续运行该过程，我们考虑如何在最后一步中生成有效的对。 如果$(x, y) \rightarrow (y, x \div y)$，那么反转这一步就意味着选择一个商$k$这样$x = ky + r$具有确保正确性和终止的约束。 这将问题转化为在边界内受控生成所有可达状态，并且可以有效地枚举这些状态。

 ## 算法演练

 关键思想是通过使用状态上的结构化 BFS 按字典顺序递增生成所有有效对来构造它们。 

1. 我们对待每一对$(x, y)$作为一种状态，并尝试理解它是如何从过程的上一步中产生的。 我们不是向前模拟，而是通过从基本满足正确性的最小配置扩展来构建有效对。 
2. 我们初始化一个结构，该结构将存储所有发现的有效对，并从其中的对开始$x = y$。 这些是稳定的，因为算法立即执行$x \div y = 1$，导致与 gcd 行为相匹配的可预测终止路径。 
3.来自任何有效对$(a, b)$，我们通过反转转换来生成新的候选者。 如果一对可以来自上一步，则它必须满足$(b, k \cdot b + a)$对于某个整数$k \ge 1$，因为这对应于逆欧几里得行为中的商步。 
4. 我们只接受在范围内生成的对$\le n$。 这确保我们永远不会在允许的状态空间之外进行探索。 
5. 我们将所有生成的对推入优先级结构中，或者以自然保留字典顺序的方式生成它们，通常通过始终扩展更小的$x$首先，维持每个扩展中的秩序。 
6. 我们继续，直到不能生成新的对。 由于每个状态对应于有界反向转换下的不同可达配置，因此状态总数在对数分支之前是线性的。 

构建完整列表后，我们通过索引到预先计算的数组来回答查询。 

### 为什么它有效

 正确性依赖于这样一个事实：有缺陷的欧几里得过程的每次有效执行都定义了唯一的商运算链。 每个有效对对应于从不违反界限的逆欧几里德步骤的有限序列$n$。 通过构造，反向生成精确地枚举这些序列，而不枚举其他序列。 字典顺序被保留，因为每次扩展都会以受控方式产生具有严格更大的第二坐标的子代，并且类似 BFS 的结构确保了发现的确定性排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    
    pairs = []
    
    # We generate all (x, y) with x >= y first in a structured way.
    # Observation-based generation: build from equal pairs downward.
    
    for y in range(1, n + 1):
        x = y
        while x <= n:
            pairs.append((x, y))
            x += y
    
    pairs.sort()
    
    for _ in range(q):
        p = int(input())
        if p > len(pairs):
            print(-1, -1)
        else:
            print(pairs[p - 1][0], pairs[p - 1][1])

if __name__ == "__main__":
    solve()
```该实现依赖于生成所有对，其中一个数字是另一个数字的倍数，这捕获了修改后的欧几里德过程的全套稳定状态。 内循环枚举算术级数$(y, y), (2y, y), (3y, y), \dots$，对应于不中断终止的有效商驱动转换。 

排序确保字典顺序$x$， 然后$y$，这是正确索引所必需的。 查询应答就是直接数组查找。 

一个微妙的实现细节是，此结构中不会出现重复项，因为每一对都是从唯一的基础生成的$y$。 生成的对总数为$\sum_{y=1}^n n/y$，即$O(n \log n)$，在限制范围内轻松拟合。

 ## 边缘情况

 当出现一种边缘情况时$y = 1$。 为了$n = 4$，我们生成对$(1,1), (2,1), (3,1), (4,1)$。 该算法将它们视为有效，因为每个都代表一个简并的欧几里得链，其中除以 1 可以保持稳定性。 前向过程永远不会减少$x$，但在反向构造中，这些状态自然地显示为基础扩展，并且只包含一次。 

另一个边缘情况是当$x = y$。 例如$(3,3)$。 向前一步产生$x = 1$，然后交换，干净地终止。 当以下情况时，该结构明确包括这些对角线：$y = x \cdot 1$，确保它们出现在正确的字典位置。 

第三种情况是边界饱和，例如$(n, 1)$。 为了$n = 5$，这会产生$(5,1)$，它出现在排序中较晚的位置。 施工保证不会错过，因为进展$y = 1$扩展到整个范围$n$，覆盖最大可能的 x 值。
