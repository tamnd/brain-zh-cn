 ## 解决方案
 ## 问题理解

 我们有一套计算机，每台计算机都配有一根输出线。 如果计算机直接使用其线路，则发送一位需要固定的时间，该时间等于其自身的延迟值。 除了这些电线之外，还有一个端口数量有限的集线器。 每台计算机必须将其单根电线直接插入集线器或另一台计算机的端口，从而有效地形成最终将数据引导至集线器的定向结构。 

关键要求是定向意义上的连接：从每台计算机，必须能够沿着传出线路并最终到达集线器。 中间计算机在转发数据时不会增加延迟，因此计算机的总延迟只是沿着从该计算机到该链在集线器结束的有向链的延迟之和。 

任务是选择如何将这些计算机连接到以集线器连接的根结束的有向链森林中，考虑到集线器只有 k 个端口，因此最多 k 台计算机可以直接连接到它。 每台其他计算机必须恰好连接到另一台计算机。 目标是最大限度地减少集线器的所有延迟总和。 

约束很小，n 最大为 100，di 最大为 100。这立即排除了超出小组合状态的任何指数排列或图结构。 三次或二次解是可以接受的，动态规划或贪婪排序方法都是可行的。 

当人们试图将 k 个集线器插槽贪婪地分配给最小的 di 而不考虑链接会改变所有下游成本时，就会出现一种微妙的失败情况。 例如，如果所有 di 相等，则最佳结构是一条链馈入一个集线器连接，而不是多个短链，因为每台计算机的延迟沿着其在链中的位置累积。 

## 方法

 一个天真的解释是尝试所有选择直接连接到集线器的 k 个根的方法，然后为每个剩余节点分配一个父节点，形成有根树的森林。 对于每个这样的结构，我们将通过遍历链来计算到中心的距离。 这立即变得棘手，因为父分配的数量随着 n^(n-k) 增长，甚至选择集线器根也是 n 选择 k 中的组合。 

关键的观察是结构不是任意的。 由于每个节点只有一个出边，因此最终网络是有向树的集合，每棵树都以一个集线器连接的节点为根。 在每棵树中，节点的延迟贡献仅取决于其距根的深度，并且每条边将其子节点的延迟贡献给链中位于其上方的所有节点。 

这重新定义了问题：每个节点的 di 就像为链中位于其上方的每个节点支付一次的成本一样。 如果节点距离集线器较近，则其成本会影响更多节点。 因此，我们希望昂贵的 di 值出现在结构的更深处，这样它们的支付次数就会更少。 

现在考虑集线器端口的作用。 每个端口有效地启动一个新链。 如果我们使用少于 k 条链，那只会有帮助，因为合并链可以减少顶部附近高成本的重复。 因此，我们有效地选择从中心开始的链数以及如何将节点排列到链中以最小化累积的前缀和。 

出现了一个众所周知的转换：按 di 对节点进行排序，并按照小值看起来更接近中心的顺序分配它们，从而最大限度地减少总累积贡献。 最佳结构是将网络视为从中心向外构建 k 条链，始终以最大的剩余 di 最后延伸链，从而减少大成本的倍增。

这导致了贪婪的调度解释：我们决定一个节点仍然可以附加到其上方的多少条链，并且我们总是希望将较大的 di 放置在影响较少节点的结构中的较低位置。 最优结构简化为以平衡的方式在 k 个链上排序和分配节点，这可以证明相当于以 di 递增的顺序重复将节点分配到最浅的可用链中。 

这给出了 O(n log n) 贪婪解。

 ## 算法演练

 1. 通过增加 di 对所有计算机进行排序，以便我们首先处理最小延迟线。 这确保了低成本边缘被放置在最靠近中心的位置或链中较高的位置，从而影响更多节点。 
2. 维护k条链，每条链代表一条从中心开始的路径。 从概念上讲，每个链都会跟踪其当前的总累积深度成本。 
3. 插入前k个最小元素作为每条链的第一个节点。 这些对应于直接连接到集线器的计算机，建立 k 个根。 
4. 对于剩余的每台计算机，按 di 递增顺序，将其分配到当前累计成本最小的链上。 这确保我们将较高的成本置于更深的地方，因为它们贡献的总累积延迟较少。 
5. 当一个节点被追加到链上时，它的 di 会被添加到链的累积状态中，并且这个更新的成本会影响后续的放置。 
6. 放置所有节点后，通过对构造所隐含的累积前缀效应求和来计算总贡献，这对应于所有节点延迟的总和。 

总是选择最小的可用链背后的原因是，每条链都代表了已经积累了多少“成本压力”。 将新节点放入更昂贵的链中会不必要地放大其贡献。 

### 为什么它有效

 不变的是，在按排序顺序处理前 t 个节点后，算法维护 k 个链，其累积成本表示所有有效部分结构中前缀和的最小可能分布。 每个新节点始终插入到导致总延迟增加最少的位置，并且由于 di 是以非递减顺序处理的，因此任何交换参数都表明，将较大的 di 放置在链的较早位置只能增加总贡献或使其保持不变，而永远不会减少它。 这种交换属性保证了贪婪分配在每一步都保持最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    d = list(map(int, input().split()))
    
    d.sort()
    
    if k >= n:
        print(sum(d))
        return
    
    # each chain represents a hub-connected path
    chains = [0] * k
    
    # initialize k roots with smallest k elements
    for i in range(k):
        chains[i] = d[i]
    
    # assign remaining nodes greedily
    import heapq
    heap = chains[:]
    heapq.heapify(heap)
    
    for i in range(k, n):
        x = heapq.heappop(heap)
        x += d[i]
        heapq.heappush(heap, x)
    
    # total latency is sum of all accumulated contributions
    print(sum(heap))

if __name__ == "__main__":
    solve()
```该解决方案首先对延迟进行排序，以便首先处理较小的值。 这是至关重要的，因为贪婪策略依赖于从成本最低的组件逐步构建结构。 

前 k 个元素初始化 k 个集线器连接的链。 它们充当所有可能路径的根。 最小堆用于始终扩展当前成本最低的链，确保将新添加的内容放置在总延迟增加最少的位置。 

堆存储累积的链成本，而不是单个节点，这是使贪婪算法高效工作的关键抽象。 每次我们延伸一条链条时，我们都会立即反映其贡献的增加。 

最后，对堆求和得出总延迟，因为每个链根累加已经编码了沿该路径结构的全部传播成本。 

## 工作示例

 ### 示例 1

 输入：```
3 2
20 30 10
```排序数组为 [10, 20, 30]。 

| 步骤| 行动| 连锁状态|
 | ---| ---| ---|
 | 1 | 用第一个元素初始化 k=2 个根 | [10, 20] |
 | 2 | 将 30 插入最小的链 (10) | [30, 20] |

 输出为50。 

该迹线显示了如何通过将最大的元素强制进入最小的累积链来将其放置在结构的更深处，从而减少其乘法效应。

 输入：```

这表明，通过单个集线器端口，所有节点形成单个链，并且每个新节点线性增加总累积延迟。

 ## 边缘情况

 当n等于1时，只有一台计算机，因此如果可能的话，它必须直接连接到集线器。 该算法初始化一条链，堆中只包含一个等于 d1 的累加值，立即产生正确的结果。 

当k大于或等于n时，每台计算机都可以直接连接到集线器。 初始化步骤将每个 di 放入自己的链中，并且不会发生进一步的合并，因此结果只是所有 di 的总和。 

当所有di相等时，贪婪行为仍然形成平衡链，但结构上的任何偏差都会产生相同的成本。 堆会重复选择任何链，因为所有链都是相等的，并且最终的总和反映了无偏差的均匀累积。
