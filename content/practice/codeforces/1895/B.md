 ## 解决方案
 ## 问题理解

 我们从多组开始$2n$整数。 任务是使用每个数字一次并将它们配对，形成$n$有序对。 每对都成为平面上的一个点，其中两个值被解释为其$x$和$y$坐标。 

一旦这些点被固定，我们就可以将它们排列在一条路径中。 该路径必须至少访问每个点一次，我们使用连续点之间的曼哈顿距离来测量其长度。 我们可以在所选点中的任何位置开始和结束。 

所以真正的自由在于两个决定。 首先，如何将数字分成对。 其次，如何对路径中的结果点进行排序。 目标是尽量减少曼哈顿的总旅行距离。 

限制很小：$n \le 100$，因此每次测试最多 200 个数字。 这很重要，因为它排除了指数配对策略或子集动态规划等任何内容。 然而，尽管理论上对于小型设备来说，暴力破解配对是可能的。$n$，它增长得非常快，因为完美匹配的数量$2n$元素是$(2n)! / (2^n n!)$，即使在适度的情况下也变得难以管理$n$。 

当许多值相同时，会出现微妙的边缘情况。 如果所有数字都相同，则每次配对都会产生相同的点，并且答案为零。 另一个极端情况是当值被分成极端时，因为最佳解决方案在很大程度上取决于平衡坐标上的大值和小值，而不是任意配对相邻​​元素。 

## 方法

 暴力方法将枚举所有可能的配对$2n$数入$n$对，然后对于每个配对计算结果点的所有排列以模拟可能的路径。 即使忽略排列并假设我们之后对点进行最佳排序，简单地枚举配对也已经主导了复杂性。 每个配对确定一组点，对于每组点，我们需要计算一条最佳路径，这本身就是曼哈顿距离下的旅行商问题。 这很快就变得不可行。 

关键的结构观察是路径结构与点的形成方式无关。 对于任何固定的点集，以最小曼哈顿行程访问所有点的最佳路径可以理解为以单调顺序连接点，并且成本本质上由坐标的分布程度决定。 这将问题从“找到一条路径”转移到“构建最小化坐标不平衡的点”。 

现在的核心思想是利用排序。 由于我们将数字配对，并且每个数字都独立贡献$x$或一个$y$，最好的策略是控制极值行为：我们希望最小化总传播，这是通过以受控对称方式将小与大配对来实现的。 具体来说，对数组进行排序允许我们将最小值与最大值进行匹配，从而平衡坐标并避免创建坐标都大或都小的点。 

排序后，我们分配第一个$n$一个坐标组和最后一个坐标组的最小值$n$其他坐标组的最大值。 按顺序将它们配对会产生坐标“均匀分布”的点，这会在按排序顺序遍历时最小化曼哈顿距离。 

这种构造之所以有效，是因为曼哈顿距离在坐标上是可加的，并且总路径成本可以解释为沿线的独立贡献之和$x$和$y$。 通过最小化每个坐标维度的不平衡，我们最小化总遍历成本。

 ## 算法演练

 我们通过排序控制坐标分配来构造解决方案。 

1. 对数组进行排序$a$。 这在小值和大值之间提供了清晰的分离，这对于平衡坐标分布至关重要。 
2. 将排序后的数组分成两半。 前半部分包含最小的$n$值，后半部分包含最大的$n$价值观。 
3. 对称配对元素：取$i$前半部分中的第 -th 元素并将其与$i$后半部分的第 - 个元素。 每对变成一个点$(x_i, y_i)$。 

这种配对确保每个点组合一个小值和一个大值，从而防止极端坐标聚类。 
4. 按照构建的顺序输出点。 任何一致的顺序都是有效的，因为最佳路径始终可以遵循这种单调结构，而不会增加成本。 

工作原理：曼哈顿距离目标实际上取决于坐标在点集中分布的距离。 如果我们要将小-小或大-大配对，我们将创建集中在平面区域的点，这会增加簇之间所需的行进距离。 将最小与最大配对迫使每个点处于平衡位置，从而最小化坐标方差。 由于两个坐标均源自相同的排序结构，因此生成的配置避免了在任何方向上不必要的扩展。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()

        # split into two halves
        left = a[:n]
        right = a[n:]

        points = []
        for i in range(n):
            points.append((left[i], right[i]))

        # output
        for x, y in points:
            print(x, y)

if __name__ == "__main__":
    solve()
```该实现完全依赖于排序和直接配对。 排序后的数组被干净地分割，每个索引产生一个点。 这里的一个常见错误是错误地混合两半之间的索引或试图交错值； 两者都打破了预期的平衡并导致次优利差。 

另一个微妙之处是我们不需要显式地构建或优化路径。 该问题保证了一旦点被固定，我们总是可以选择一条路径，并且该构造确保任何合理的遍历顺序都会产生最小的可能成本。

 ## 边缘情况

 当所有值都相同时，排序会产生两个相同的一半。 将它们配对会产生相同的点，并且每个曼哈顿距离都为零。 该算法自然地处理这个问题，因为每个坐标分配都保持相等。 

当值严格递减时，排序会将它们翻转为递增顺序，并且配对仍然会产生平衡的极值。 例如，$[6,5,4,3,2,1]$变成左边$[1,2,3]$和对的$[4,5,6]$，配对顺利进行，无需任何特殊外壳。 

当存在重复项时，它们在排序后均匀分布在两半上。 这确保了坐标不会变得过度集中，并且无论重复模式如何，配对都保持稳定。
