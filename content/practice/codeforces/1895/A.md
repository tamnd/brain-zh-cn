 ## 解决方案
 ## 问题理解

 数轴包含三个重要位置。 Monocarp 从位置开始`0`，胸部处于位置`x`，钥匙位于位置`y`。 

要打开箱子，Monocarp 最终必须站在与箱子相同的位置，同时已经携带钥匙。 步行每单位距离花费一秒。 拿起或放下箱子和钥匙不需要任何费用。 

复杂的是，箱子最多可以携带`k`总共秒。 如果钥匙尚未在前往宝箱的途中，Monocarp 可能需要将宝箱移近钥匙，但携带距离不能超过`k`。 

输入最多包含 100 个测试用例，所有坐标最多为 100。约束很小，但真正的目标是找到立即给出答案的数学观察。 

一个常见的错误是认为 Monocarp 必须始终在接触胸部之前到达钥匙。 但事实并非如此，因为他被允许携带箱子。 

考虑：```
x = 5, y = 7, k = 2
```他到达位置 5 处的箱子，将其移动 2 个单位到达位置 7，拿起钥匙，然后打开箱子。 答案是 7，而不是 12。 

另一个容易犯的错误是总是回答`max(x, y)`当钥匙超出箱子时。 

考虑：```
x = 5, y = 8, k = 2
```钥匙距离宝箱有3个单位，但Monocarp只能携带2个单位的宝箱。 他把它带到位置 7，走到位置 8 拿钥匙，然后返回到位置 7。答案是 9，而不是 8。 

当钥匙位于箱子前面时，会出现第三种边缘情况。```
x = 10, y = 5, k = 0
```Monocarp 只需在通往宝箱的路上捡起钥匙即可。 答案是 10。任何试图将箱子搬到这里的逻辑都是不必要的。 

## 方法

 暴力视图是对 Monocarp 的每个可能位置进行建模，包括他是否有钥匙、箱子当前在哪里以及剩余的携带耐力。 然后我们可以对结果状态空间运行最短路径搜索。 

这是可行的，因为所有动作都有非负成本并且状态空间是有限的。 如果坐标以 100 为界，这样的解决方案甚至可以实现。 问题在于它完全忽略了数轴的结构和所涉及的非常简单的几何图形。 

关键的观察是只有两个相对顺序很重要。 

如果钥匙位于胸部或胸部之前（`y < x`），Monocarp 向宝箱走去并到达钥匙。 他免费拿起它并继续`x`。 胸部永远不需要移动。 答案很简单`x`。 

有趣的情况是当钥匙超出箱子时（`y > x`）。 

单果树必须首先到达胸部，花`x`秒。 

箱子和钥匙之间的剩余间隙是：```
d = y - x
```如果`d <= k`，他可以将箱子一直带到钥匙处。 总时间变为`x + d = y`。 

如果`d > k`，他把胸部尽可能地抬高，准确地说`k`单位。 胸部停在位置`x + k`。 

还剩一段距离：```
r = d - k
```单果树散步`r`单位到键，然后`r`单位回到胸部。 那成本`2r`额外的秒数。 

总计变为：```
x + k + 2(d - k)
= x + 2d - k
```自从`y = x + d`，也可以写成：```
y + (d - k)
```一个紧凑的公式是：```
x,                     if y < x
y + max(0, y - x - k), otherwise
```| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(S)| O(S)| 不必要|
 | 最佳 | 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`x`,`y`， 和`k`。 
2.如果`y < x`，在到达宝箱之前就遇到了钥匙。 途中捡起钥匙，继续前往宝箱。 输出`x`。 
3. 否则计算间隙`d = y - x`。 
4. 如果`d <= k`，宝箱可以一直带到钥匙处。 输出`y`。 
5.否则胸部只能移动`k`单位。 剩余距离为`d - k`。 
6. Monocarp 必须走完剩余的距离才能拿到钥匙，然后走同样的距离回到箱子。 输出`y + (d - k)`。 

### 为什么它有效

 当`y < x`，每个有效的解决方案最终都必须到达位置`x`，关键就在那条路上。 到达胸部时`x`已经足够了，所以`x`是最优的。 

什么时候`y > x`, Monocarp 必须先花`x`几秒钟到达胸部。 将箱子移向钥匙总是有益的，因为它可以减少未来它们之间的距离。 最好的策略是使用尽可能长的承载距离，最多`k`或直到箱子到达钥匙。 任何剩余的间隔都必须穿过两次，一次收集钥匙，一次返回箱子。 上面的公式准确地解释了这些不可避免的移动，因此不存在更短的路线。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    x, y, k = map(int, input().split())

    if y < x:
        print(x)
    else:
        print(y + max(0, y - x - k))
```第一个分支处理在箱子之前遇到钥匙的情况。 不需要携带，所以答案很简单，就是胸前的位置。 

在第二个分支中，钥匙位于箱子之外。 价值`y - x - k`代表箱子到钥匙间隙中无法通过携带箱子来覆盖的部分。 如果该数量为负数，则宝箱直接到达钥匙，因此额外成本为零。 否则，剩余距离对超出答案的贡献恰好一次`y`，产生公式`y + max(0, y - x - k)`。 

所有计算都适合标准整数类型，并且不存在棘手的边界条件，因为该公式自然处理`k = 0`和`d = k`。

 ## 边缘情况

 考虑：```
1
10 5 0
```该算法看到`y < x`并立即返回`10`。 莫诺卡普一边走向宝箱一边拿起钥匙。 无需携带。 输出是正确的。 

考虑：```
1
5 7 2
```这里`y > x`，间隙为`2`。 自从`2 <= k`，算法返回`y = 7`。 箱子可以直接拿到钥匙处。 不会发生额外的回溯。 

考虑：```
1
5 8 2
```差距是`3`，大于`k`。 未被覆盖的部分是`3 - 2 = 1`。 算法返回`8 + 1 = 9`。 这个额外的单位完全对应于从重新安置的箱子到钥匙再回来的步行。 

考虑：```
1
4 9 0
```差距是`5`，并且无法携带。 公式给出`9 + 5 = 14`。 Monocarp 在 4 秒内走到宝箱，然后必须从 4 走到 9，再回到 4，再增加 10 秒。 总数为14，与公式完全匹配。
