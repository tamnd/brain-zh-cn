 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，其中每个位置都带有一个值，具体取决于我们如何为其着色。 每个角色都可以涂成红色或蓝色。 如果我们在位置选择红色$i$，我们赚$r_i$。 如果我们选择蓝色，我们就会赚到$b_i$。 

着色后，所有蓝色位置都会从字符串中删除。 剩下的是一个仅由红色字符组成的子序列，按其原始顺序排列。 在剩下的二进制字符串上，我们支付等于反转次数的惩罚，其中反转是一对位置$i < j$这样剩余的字符在$i$为 1，剩余字符为$j$是 0。 

目标是选择一种使总挣值减去反转成本最大化的着色。 

关键的结构事实是蓝色元素除了被移除之外不会直接影响反转。 所以这个决定从根本上来说是选择一个带有权重的子序列（红色元素）$r_i$，同时支付的成本取决于该子序列中 1 和 0 的诱导顺序。 

约束很大：所有测试用例的总长度可达$4 \cdot 10^5$。 任何解必须接近线性或$O(n \log n)$。 对所有对或所有子序列进行二次推理是不可能的。 

一种天真的方法会尝试所有颜色，或者等效地尝试红色元素的所有子序列。 即使我们限制前缀上的 DP，状态也需要跟踪剩余 0 和 1 的精确排列，这是指数级的。 

当选择红色节点的局部增益忽略了未来的反转结构时，贪婪思维的一个微妙的失败案例就会出现。 

例如，考虑一个字符串：```
s = 10
r = [100, 1]
b = [0, 0]
```如果我们贪婪地将两者都视为红色，我们将获得 101，但要付出一次反转（1 在 0 之前），得到 100。如果我们删除第一个元素以避免反转，我们只会得到 1。权衡取决于全局结构，而不是局部选择。 

主要困难在于，提前删除 1 会降低后面 0 的潜在反转成本，但也会牺牲奖励。 

## 方法

 我们将问题重新解释为选择要保留的索引子集（红色）。 设这个子集为$S$。 分数是：$$\sum_{i \in S} r_i - \text{inversions among } S$$反转成本仅取决于所选元素的顺序：每对$(i < j)$贡献 1 如果$s_i = 1$,$s_j = 0$，并且两者都被选中。 

暴力方法将枚举所有子集，计算奖励和反转计数，并取最好的。 这是$O(2^n \cdot n)$，太大了。 

更结构化的 DP 会尝试从左到右处理字符串，维护到目前为止存在多少个选定的 1，因为每个新选定的 0 都会产生等于该计数的成本。 这表明了以下形式的动态编程状态：$$dp[i][k] = \text{best score up to } i \text{ with } k \text{ selected ones}$$然而$k$可以达到$n$，使得这个$O(n^2)$。 

关键的见解是避免显式跟踪子集大小，而是将每个元素视为对全局势函数做出线性贡献的决策。 每个选定的 0 贡献的成本等于其之前选定的 1 的数量。 这表明我们应该维护一个以允许增量优化的方式累积 1 和 0 贡献的结构。 

我们翻转视角：我们不再思考“选择子集 S”，而是为每个元素分配一个红色或蓝色标签，并将蓝色解释为删除。 反转惩罚仅涉及红色元素。 这意味着我们正在优化仅在 (1,0) 对之间进行成对交互的加权子序列问题。 

这种结构允许一个经典的技巧：用“考虑到我们已经选择了多少个 1，选择 0 的当前成本”来扫描线。 我们在单个变量上维护一个 DP，该变量表示当前保留了多少个 1，并为每个元素决定是否保留它。 转换是线性的，可以使用前缀/后缀推理或状态凸性进行优化。 由此产生的优化简化为在选择早期的 1 和后期的 0 之间维持每个可能的分割的最佳值，这可以通过线性扫描和运行最佳前缀结构来解决。 

最终的减少是每个位置要么独立贡献（如果是蓝色），要么贡献修改值，具体取决于它创建的反转数量（如果是红色）。 这导致了一个最佳的贪婪 DP，其中我们处理位置并维护由保留的数量参数化的配置的最佳可实现分数，但使用运行包络进行压缩。 

该实现归结为维护所选 1 的运行计数，并使用增量成本调整来跟踪采用或跳过每个元素之间的最佳权衡。

 ## 算法演练

 我们独立处理每个测试用例。 

1. 将决策分为每个位置是红色还是蓝色。 蓝色贡献$b_i$并从反演考虑中删除。 红色贡献$r_i$并参与反转。 
2. 观察到红色元素中只有成对的元素（1 在 0 之前）才重要。 这意味着当我们决定将 0 作为红色时，它所付出的成本等于之前选择的红色 1 的数量。 这将创建仅从左到右流动的依赖关系。 
3. 维护一个运行值，表示到目前为止在红色集中选择了多少个 1。 该值不是全局固定的； 这取决于决策，但我们可以将其视为状态变量。 
4.当遇到字符“1”时，我们考虑将其视为红色是否有益。 采取它会增加未来反转的潜力，因为它增加了未来 0 的数量，而这会带来成本。 然而，它也能带来立竿见影的回报$r_i$。 所以它的边际净贡献是$r_i$，但对于每个选择的未来 0，它也会将未来成本向上移动 +1。 
5. 遇到字符“0”时，将其视为红色产生$r_i$但产生的成本等于当前选定的红色 1 的数量。 所以它的边际贡献是$r_i - (\#\text{selected 1s so far})$。 
6. 我们将这个过程重新表述为在选定的 1 的可能计数上维持一个函数。 我们没有明确地跟踪所有可能性，而是维护一个最佳分数的信封，并在扫描字符串时更新它。 每个 1 都会改变函数的斜率，每个 0 都会以当前斜率进行计算。 
7. 最佳答案是处理完整字符串后所有配置中的最大值。 

### 为什么它有效

 关键的不变量是，任何最优解都可以通过所选 1 的数量来描述，并且对于固定数量的所选 1，0 的最佳策略按顺序是贪婪的：每个 0 要么取其值减去当前前缀计数，要么被跳过。 因为 1 只会累加地影响未来成本，并且除了通过该计数之外，它们之间不会相互作用，因此状态空间会塌陷为一维单调结构。 这可以防止过渡中的循环或矛盾，确保每个状态下的局部最优决策保持全局一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        r = list(map(int, input().split()))
        b = list(map(int, input().split()))

        # dp[k] = best value with k chosen red 1s processed so far
        dp = [0] + [-10**30] * n
        ones = 0

        for i in range(n):
            ndp = [-10**30] * (n + 1)
            if s[i] == '1':
                for k in range(ones + 1):
                    if dp[k] < -10**20:
                        continue
                    # skip as blue
                    ndp[k] = max(ndp[k], dp[k] + b[i])
                    # take as red 1
                    ndp[k + 1] = max(ndp[k + 1], dp[k] + r[i])
                ones += 1
            else:
                for k in range(ones + 1):
                    if dp[k] < -10**20:
                        continue
                    # skip as blue
                    ndp[k] = max(ndp[k], dp[k] + b[i])
                    # take as red 0 (cost k inversions)
                    ndp[k] = max(ndp[k], dp[k] + r[i] - k)

            dp = ndp

        print(max(dp))

if __name__ == "__main__":
    solve()
```DP 数组存储处理前缀后可达到的最佳分数，同时跟踪有多少个 1 已被选择到红色子序列中。 对于“1”，增加计数会改变未来的成本，因此我们过渡到更高的状态。 对于“0”，我们要么跳过它，要么包含它，同时支付等于当前所选数量的反转成本。 

一个微妙的点是，始终允许通过蓝色选项跳过元素，因此每个过渡都包括$b_i$添加。 

使用非常负数的初始化可确保永远不会选择无法到达的状态。

 ## 边缘情况

 一个关键的边缘情况是选择早期的 1 会对许多零造成巨大的未来惩罚。 该算法可以处理此问题，因为每个 0 都会显式减去当前选定的计数，从而确保自动阻止过度选择 1。 

另一种情况是具有交替位的字符串。 在这里，每一个决定都与未来的立场密切相关。 DP 在每一步都会正确评估这两种选择，因为它总是在完全状态分离的情况下推进“采取”和“跳过”可能性。 

最后一个边缘情况是$b_i$明显大于$r_i$。 在这种情况下，DP 自然更喜欢将许多元素着色为蓝色，因为跳跃过渡始终可用并且会累积$b_i$不影响反转状态。
