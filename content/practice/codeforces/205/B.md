 ## 解决方案
 ## 问题理解

 给定一个整数数组，一个操作包括选择一个连续的段并将该段内的每个元素恰好加一。 我们可以多次重复此操作。 完成所有操作后，我们不需要匹配固定的目标数组； 相反，我们只需要最终的数组是非递减的。 

因此，任务是了解需要多少次范围递增操作才能将原始数组转换为从左到右读取时永远不会减少的数组。 

关键的微妙之处在于，我们可以自由选择数组的最终形状，只要它是非递减的并且只能通过在子数组上添加增量来获得。 我们不允许减少值，只能使用段向上“推”数组的一部分。 

约束 n ≤ 100000 意味着我们无法显式模拟操作。 每个操作都可以接触 O(n) 个元素，如果简单地应用，即使是几千个操作也已经太慢了。 任何有效的解决方案都必须将问题简化为单个线性扫描。 

一个天真的但自然的错误是认为我们可以通过增加后缀或前缀来贪婪地“修复”局部反转，而不仔细计算操作如何重叠。 

例如，考虑 [5, 1, 1]。 粗心的方法可能会尝试独立提高第二个和第三个元素，但由于操作作用于范围，固定一个位置可能会无意中影响较早的位置。 

另一个误导性的情况是数组已经是非递减的，例如 [1, 2, 3, 4]。 任何正确的解决方案都必须立即返回 0，而不是尝试进一步“改进”任何内容。 

另一种不同的边缘场景是数组严格递减，例如 [4, 3, 2, 1]。 在这里，每个相邻的液滴都独立地对所需操作的数量做出贡献，但为什么这些贡献不以复杂的方式相互作用并不明显。 

## 方法

 蛮力观点从操作的定义开始。 每个操作都会将选定的段加一，因此我们可以尝试模拟所有操作序列并检查数组何时变为非递减。 即使将我们限制为固定数量的操作，分支因子也是巨大的，因为每个步骤都允许 O(n²) 可能的分段。 这很快就会使操作数量呈指数级增长，即使对于小型数组也是不可行的。 

一个更结构化的粗暴想法是固定目标非递减数组 b，其中 b[i] ≥ a[i]，然后尝试将差异 b - a 表示为范围增量之和。 这相当于将非负数组分解为间隔更新，但搜索所有有效的 b 仍然太大。 

关键的简化来自于颠倒视角。 我们不是构建任意的最终数组，而是关注相邻违规如何强制操作。 如果在某个位置 i 我们有 a[i] > a[i+1]，那么右侧与左侧相比太小。 由于我们只能增加值，因此解决此问题的唯一方法是将位置 i+1 增加得足够多，以便它赶上 a[i]。 该间隙的每个单位必须通过影响 i+1 但不同等影响 i 的某些操作来“交付”，这意味着独立于其他位置的结构成本。 

这导致了线性分解，其中每个向下的步骤都直接贡献于答案。

 | --- | --- | --- | --- |

 | 最佳相邻液滴计数 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从左到右扫描一次数组，并测量每个相邻的减少对操作总数的贡献程度。

1. 从初始化为零的运行答案开始。 该变量将累积所需范围操作的数量。 
2. 从第一个元素到倒数第二个元素迭代数组。 在每个位置 i，比较 a[i] 和 a[i+1]。 
3. 如果a[i]小于或等于a[i+1]，则不执行任何操作。 该对已经满足局部非递减顺序，因此不需要强制操作来修复该边界。 
4. 如果 a[i] 大于 a[i+1]，则计算差值 d = a[i] - a[i+1]。 将此值添加到答案中。 这表示为了消除局部下降而必须应用于相对于 i 的位置 i+1 的最小单位增量数。 
5. 继续扫描直到阵列末端，累积所有此类阳性液滴。 
6. 输出最终累加值。 

步骤 4 背后的原因是，每个减少单位对应于一个独立的校正“层”，必须通过在 i+1 或之后开始且不完全覆盖 i 的某种范围操作来引入该校正。 这些层不会干扰不同的位置，因为每个相邻的下降点强制执行其自己的所需增量的最小数量。 

### 为什么它有效

 每个操作都会将连续段恰好增加 1，因此任何最终效果都可以视为在数组上堆叠单位高度间隔覆盖。 相邻元素 a[i] 和 a[i+1] 之间的差异决定了与左侧相比，右侧必须多出现多少层，才能使最终数组不递减。 

每当 a[i] > a[i+1] 时，至少 a[i] - a[i+1] 操作必须为位置 i+1 贡献额外的高度，而不会同等地为位置 i 贡献。 没有任何操作可以同时“避免”所有此类约束，因此这些要求独立地添加到所有相邻对上。 这种独立性使得正下降的总和既是必要的也是充分的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    ans = 0
    for i in range(n - 1):
        if a[i] > a[i + 1]:
            ans += a[i] - a[i + 1]
    
    print(ans)

if __name__ == "__main__":
    solve()
```该实现是对只有向下转换才重要的观察结果的直接翻译。 该循环仅考虑每个相邻对一次，并且累加器存储消除所有局部减少所需的总强制补偿。 无需模拟操作或构建最终阵列。 

一个常见的实现错误是尝试显式维护转换后的数组或模拟范围增量。 这是不必要的，因为答案仅取决于局部差异，而不取决于不断变化的全球结构。

 ## 边缘情况

 对于像 [10] 这样的单元素数组，相邻对上的循环根本不执行，因此答案仍然为零，这与单个值一般不减的事实相匹配。 

对于严格递减数组，例如 [5, 4, 3, 2]，每个相邻对都独立贡献。 该算法累加 (5-4) + (4-3) + (3-2) = 3，这与每次下降引入一个单独的所需补偿单元的事实相匹配。 

对于已经恒定的数组，例如 [7, 7, 7, 7]，没有对满足 a[i] > a[i+1]，因此答案始终保持为零，从而确认不需要范围操作。
