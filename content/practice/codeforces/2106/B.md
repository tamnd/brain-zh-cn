 ## 解决方案
 ## 问题理解

 我们得到一个列表，它必须是从 0 到 n−1 的数字排列。 当我们从左到右揭示这种排列时，我们计算一个运行值：在每个前缀之后，我们取该前缀中缺少的最小非负整数。 随着更多元素的出现，该值会随着时间的推移而变化，并且每个前缀都会用其当前值绘制一个单元格。 

任务不是计算固定排列的着色。 相反，我们必须构造排列本身，以便特定颜色 x 在生成的绘制条中出现尽可能多的次数。 

关键的交互作用是排列中元素的顺序和前缀的 MEX 移过 x 的时刻之间的交互。 由于 MEX 仅取决于出现了从 0 开始的哪些值，因此排序决定了 MEX 保持等于特定值的时间长度。 

约束足够大，任何解决方案对于每个测试用例都必须是线性的。 n 的总和最大为 2×10^5，这排除了任何二次方或涉及每个候选排列的重复模拟的情况。 施工必须是直接的。 

当 x = n 时，会出现微妙的边缘情况。 在这种情况下，只有在所有数字 0 到 n−1 都出现之后，MEX 才等于 n。 这意味着它只发生在最后的前缀处，因此无论排列如何，答案始终为 1。 将 x 视为正常值的天真尝试会错误地尝试将 MEX “延迟”到 n 以上，这是不可能的。 

另一个边缘情况是 x = 0。这里 MEX 最初为 0，一旦出现 0 就变为 1。 因此，我们希望尽可能推迟放置 0，以延长颜色 0 的初始运行时间。 

## 方法

 一种强力的想法是生成所有排列并模拟每个排列的 MEX 过程，计算颜色 x 出现的次数。 这是正确的，但不可行。 有n个！ 排列，甚至评估一个排列的成本为 O(n)，因此这种方法是一个天文数字。 

为了优化，我们需要了解是什么让 MEX 对于连续前缀保持等于 x。 当所有数字 0 到 x−1 都出现在前缀中，但 x 本身尚未出现时，MEX 恰好等于 x。 一旦插入 x，MEX 就会跳转到大于 x 的值。 

这意味着我们希望尽可能长时间地延迟 x 的插入，同时确保所有较小的数字足够早地出现，以便 MEX 已经到达 x。 在那一刻之后，插入 x 之前的每个附加元素都会使 MEX 固定在 x，从而为我们提供所需的恒定颜色拉伸。 

唯一真正的决定是 x 相对于数字 0 到 x−1 的位置。 一旦这些较小的数字都存在，我们就可以自由地将所有大于 x 的数字放置在任何地方，而不会影响 MEX 为 x，只要 x 仍然缺失。 

这导致了一个简单的最优结构：首先放置所有大于 x 的数字，然后放置 0 到 x−1，最后将 x 放置在末尾。 这会最大化前缀包含所有小于 x 但不包含 x 本身的值的时间间隔。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了|
 | 最佳施工| O(n) | O(n) | 已接受 |

 ## 算法演练

1. 将排列分成三个概念组：大于 x 的数字、从 0 到 x−1 的数字以及单个值 x 本身。 这种分离是基于每个组如何影响 MEX 值。 
2. 将所有严格大于 x 的数字放在排列的开头。 这些值无助于形成确定 MEX = x 的前缀，但它们也不会干扰它。 
3. 紧随其后放置从 0 到 x−1 的所有数字。 这确保了一旦该块完全包含在前缀中，将 MEX 推至 x 所需的每个值都已出现。 
4. 尽可能晚地放置 x，最好放在最后。 这最大化了所有较小值都存在但 x 仍然不存在的前缀数量，这正是 MEX 等于 x 的条件。 
5. 输出构建的序列。 

关键思想是，一旦前缀包含从 0 到 x−1 的所有值，MEX 就会变成 x 并保持在那里，直到 x 出现。 我们正在最大限度地延长最后一个事件的延迟时间。 

### 为什么它有效

 前缀的 MEX 完全由缺失的最小值决定。 要使 MEX 等于 x，必须同时满足两个条件：从 0 到 x−1 的每个值都必须已经存在，并且 x 必须还不存在。 一旦两者都满足，添加任何大于 x 的值都不会更改 MEX，因为它不会填充低于 x 的任何缺失整数。 因此，在 0 到 x−1 第一次完整出现之后且 x 之前的每个位置都有助于颜色 x 的有效出现。 该构造通过确保所有小值在延迟 x 的同时尽早出现来最大化此间隔。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, x = map(int, input().split())

    if x == n:
        # MEX can only become n at full prefix
        print(*range(n))
        continue

    res = []

    # first put all values > x
    for i in range(x + 1, n):
        res.append(i)

    # then values < x
    for i in range(x):
        res.append(i)

    # finally x
    res.append(x)

    print(*res)
```该实现直接遵循以下观察结果：只有 x 相对于 [0, x−1] 的相对位置很重要。 大于 x 的值可以放置在 x 之前的任何位置，而不会影响 MEX 何时变为 x，因此我们可以安全地将它们放在前面。 循环边界很重要：第一个循环从 x+1 开始，排除 x 本身，第二个循环开始到 x−1（包括 x−1）。 

特殊情况 x = n 避免了 x 超出排列范围的空概念条件； 在这种情况下，最佳排列是无关紧要的，因为 MEX 在最终前缀之前永远不会等于 n。

 我们构建排列。

 | 2 | 值 < 2 → [0, 1] | [3, 0, 1] |

 | 4 | [3, 0, 1, 2] | 4 |

 颜色 2 只出现一次。 该结构确保我们尽早达到 MEX = 2 并保持稳定直到 x 出现。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, x = map(int, input().split())
        if x == n:
            out.append(" ".join(map(str, range(n))))
            continue

        res = []
        for i in range(x + 1, n):
            res.append(i)
        for i in range(x):
            res.append(i)
        res.append(x)
        out.append(" ".join(map(str, res)))

    return "\n".join(out)

 ## 边缘情况

 当 x = n 时，算法采用恒等排列。 对于像 n = 3, x = 3 这样的小例子，构造会产生 [0, 1, 2]。 只有在看到所有元素后，MEX 才会达到 3，因此最终的前缀单独贡献目标颜色。 

当 x = 0 时，构造将所有其他值放在前面，然后将 0 放在最后。 对于 n = 4、x = 0，我们得到 [1, 2, 3, 0]。 每个前缀的 MEX 都保持为 0，直到出现 0，这是可实现的最大跨度。 

当 x 位于中间时，例如 n = 6、x = 2，序列 [3, 4, 5, 0, 1, 2] 确保一旦出现 0 和 1，MEX 就变为 2 并保持在那里，直到追加 2，从而最大化颜色 2 单元格的数量。
