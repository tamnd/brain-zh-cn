 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串`s`长度`n`，我们想象创造`n`通过恰好翻转一位来创建新字符串`s`在每个位置。 生成的字符串被排列为`n × n`木板。 我们的目标是计算总数`1`在此板上。 

例如，如果`s = 101`（长度 3），行将生成如下：第一行翻转第一位，给出`001`; 第二行翻转第二位，给出`111`; 第三行翻转第三位，给出`100`。 全部计数`1`这些行中的 s 总共为 5。 

限制很小：`n`最多可以有 10 个，并且最多可以有 1000 个测试用例。 由于板上的单元格总数为`n^2`，最坏情况下的单元数量为 100。这表明即使直接模拟也是可行的。 然而，理解该模式可以立即获得数学公式，从而避免了嵌套循环的需要。 

非明显的边缘情况包括以下情况`s`就是全部`0`或全部`1`s。 为了`s = 0000`，翻转任何一位都会恰好创建一个`1`在该行中，所以总数`1`s 等于`n`。 为了`s = 1111`，翻转一位变成a`1`进入`0`，所以总数`1`s 等于`n*(n-1)`。 一个简单的实现，简单地求和`1`进入`s`对于每一行，如果不考虑翻转位，就会在这些极端情况下产生错误的结果。 

## 方法

 最直接的解决方案是蛮力：迭代每一行，用翻转的位构造字符串，并计算其数量`1`s。 这是正确的，因为它确实模拟了电路板，但其复杂性是`O(n^2)`每个测试用例。 和`n`最多 10，这仍然可行，因为`n^2`最多 100，在 1000 个测试用例中进行 100,000 次操作，这是可以接受的。 

更优雅的解决方案是注意每个位对最终计数的贡献。 如果有点在`s`是`1`，它出现在除翻转的行之外的所有行中。 如果有点在`s`是`0`，它仅在其翻转的行中起作用。 让`ones`是`1`进入`s`。 那么总计数为`1`板上的 s 是`ones * (n - 1) + (n - ones) * 1 = ones * (n - 1) + (n - ones) = ones * (n - 2) + n`。 这个公式直接给出了答案`O(n)`计算时间`1`s，这比构建整个电路板更快。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个测试用例的 O(n²) | O(n²) | 已接受此问题 |
 | 数学| 每个测试用例 O(n) | O(1) | O(1) | 最佳，已接受|

 ## 算法演练

 1.读取测试用例数量`t`。 我们将重复计算`t`次。 
2. 对于每个测试用例，读取整数`n`和字符串`s`。 
3. 数一下数量`1`进入`s`并将其存储在变量中`ones`。 
4. 计算总数`1`使用公式在板上 s`total_ones = ones * (n - 2) + n`。 
5. 打印`total_ones`。 

为什么它有效：每一位`s`以可预测的方式对总量做出贡献。 一个`1`保留在除其自己的翻转行之外的每一行中，而`0`仅在其翻转的行中起作用。 将所有头寸的这些贡献相加可以保证正确的总数，而无需构建董事会。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    ones = s.count('1')
    total_ones = ones * (n - 2) + n
    print(total_ones)
```代码首先读取测试用例的数量。 对于每个测试用例，它读取`n`和二进制字符串`s`。 计算数量`1`与`s.count('1')`给出了原始字符串的贡献。 应用派生公式得出的总数`1`s 在黑板上。 这`strip()`调用确保没有换行符干扰计数。

 ## 边缘情况

 对于`s = 0`（单个字符），棋盘上只有一个单元格，该单元格变为`1`翻转后，总计为 1。对于`s = 1`，唯一的行翻转`1`到`0`，总计为 0。公式`total_ones = ones*(n-2)+n`自动处理这些：`n=1`和`ones=0`，总计 = 0*(1-2)+1=1； 为了`ones=1`，总计 = 1*(1-2)+1=0。 

对于所有的字符串`1`s,`s = 1111`，我们有`ones=4`和`n=4`, 给予`total_ones = 4*(4-2)+4=12`。 每一个原创`1`出现在 4 行中的 3 行中，确认棋盘总和而不构建它。 这表明即使极端的输入也能在没有特殊大小写的情况下产生正确的计数。
