 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 的数字排列，我们需要回答许多独立的查询。 每个查询选择一个子数组范围$[l, r]$和目标值$k$。 我们想象在该固定范围上执行标准的二分搜索过程，即使数组未排序。 

在这个模拟二分搜索的每一步中，我们都会查看当前区间的中点。 如果中点已经包含$k$，搜索成功。 否则，如果中点值小于$k$，我们继续右半部分； 如果它更大，我们继续到左半部分。 给定数组值，这个过程是完全确定的。 

在搜索开始之前，我们可以选择里面的一些索引$[l, r]$，但我们被禁止选择位置$k$。 我们可以自由地排列所选索引处的值。 目标是让二分查找成功到达$k$使用尽可能少的选定索引。 

所以任务是：对于每个查询，确定我们必须“本地重新排列”的最小元素数量，以便二分搜索能够正确运行并最终到达$k$，或者报告说这是不可能的。 

约束很严格：总计$n$和总计$q$所有测试用例最多可达$2 \cdot 10^5$。 这立即排除了任何二分搜索的每次查询模拟与范围内的重新计算相结合，因为即使$O(n)$在最坏的情况下，每个查询已经太慢了。 

关键的困难在于二分查找不依赖于全局排序，而是依赖于一系列中点比较。 一个天真的错误是假设我们只需要确保“所有较小的向左，所有较大的向右”，但我们没有对段进行排序。 我们只修复有限数量的位置，二分搜索路径的结构很重要。 

出现微妙的边缘情况时$k$不存在于初始搜索间隔中。 尽管我们可以重新排列元素，但我们无法移动$k$本身或从范围之外引入。 如果$k \notin [l, r]$，不可能立即成功。 

## 方法

 暴力方法会尝试模拟二分搜索路径，并在每个访问的中点决定是否需要“修复”该位置，以便它将搜索引向正确的方向。 对于固定查询，我们可以模拟二进制搜索路径$[l, r]$，并且每当中点值与最终达到所需值相矛盾时$k$，我们将其视为需要修改。 然后我们会尝试全局决定选择哪些指数来同时解决所有矛盾。 

这很快就会变得复杂，因为如果单个选定的索引位于二分搜索路径上，则它可以解析多个步骤，并且不同的路径在查询之间以非平凡的方式重叠。 每个查询的简单重新计算也可能会重新运行二进制搜索逻辑$O(n)$病理病例中的步骤，导致$O(nq)$，太大了。 

关键的观察是，固定段上的二分搜索不是任意的：它总是访问一组确定性的索引，形成二叉分解树$[l, r]$。 每个中点定义了一个决策约束：我们向左还是向右取决于比较$p[m]$和$k$。 为了使搜索成功，沿途的每一个决定$[l, r]$下降到$k$必须与真实的相对顺序一致$k$。 

我们将指数分为三类$k$：值小于$k$，等于$k$，并且大于$k$。 的位置$k$是固定的，二分查找路径从$[l, r]$到$pos(k)$必须始终朝着它前进。 这意味着路径上的每个中点都会施加方向要求：如果中点位于$pos(k)$，我们必须确保它不会错误地向左或向右引导我们； 右侧同样如此。 

关键的减少是二分搜索访问的每个中点要么已经正确运行，要么必须通过将其索引包含在所选集合中来修复。 由于我们可以任意重新排序所选索引，因此只要我们选择足够多的索引来满足路径上的所有“错误决策”，我们总是可以在它们之间分配正确的值。 

这将问题简化为计算沿二分搜索路径有多少个中点位置与所需的方向不一致$k$，在可行性约束下，由我们有多少个可用的小值和大值决定$k$。 

## 算法演练

 1. 预先计算排列中每个值的位置，以便我们可以定位$pos(k)$在$O(1)$。 这是必要的，因为二分搜索路径取决于位置$k$物理上坐着。 
2.如果$pos(k)$不在里面$[l, r]$，立即返回$-1$。 二分搜索无法到达搜索间隔之外的目标，因为没有操作允许移动$k$进入范围。 
3. 模拟从以下位置开始的二分查找区间过程$[l, r]$，但我们不是搜索一个值，而是跟踪当前中点是位于$pos(k)$。 
4. 对于每个中点$m$， 比较$m$和$pos(k)$。 如果$m = pos(k)$，这一步无需修改。 
5. 如果$m < pos(k)$，二分查找必须向右进行。 这意味着$p[m]$必须小于$k$。 如果目前$p[m] > k$，这个位置是“错误的”，必须包含在所选集合中。 
6. 如果$m > pos(k)$，二分查找必须向左。 这意味着$p[m]$必须大于$k$。 如果目前$p[m] < k$，这也是一个需要选择的“错误”位置。 
7. 沿二分搜索路径计算所有此类不匹配的中点位置。 答案是所需修正的数量，因为每个选定的索引都可以重新排列以满足正确的边约束。 

### 为什么它有效

 The binary search path forms a fixed sequence of decision points, and each decision depends only on whether the midpoint value is smaller or larger than$k$。 任何不正确的决定都会迫使我们推翻该立场，因为保持不变将永久引导搜索远离$pos(k)$。 每个覆盖对应于选择该索引，并且因为我们可以任意排列所选索引，所以我们始终可以为它们分配一致的值，以便所有更正的位置同时正确运行。 该过程绝不会引入新的冲突，因为每个校正后的指标在约束方面都是独立的：它只需要满足一个相对于$k$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        p = list(map(int, input().split()))
        
        pos = [0] * (n + 1)
        for i, v in enumerate(p, 1):
            pos[v] = i
        
        for _ in range(q):
            l, r, k = map(int, input().split())
            pk = pos[k]
            
            if pk < l or pk > r:
                print(-1, end=" ")
                continue
            
            d = 0
            L, R = l, r
            
            while L <= R:
                m = (L + R) // 2
                if m == pk:
                    break
                
                if m < pk:
                    if p[m - 1] > k:
                        d += 1
                    L = m + 1
                else:
                    if p[m - 1] < k:
                        d += 1
                    R = m - 1
            
            print(d, end=" ")
        print()

if __name__ == "__main__":
    solve()
```该解决方案首先构建一个位置图，以便定位$k$是每个查询的恒定时间。 然后，每个查询模拟二分搜索间隔更新过程，维护与所需方向相矛盾的中点位置计数器$k$。 

重要的实现细节是中点索引和位置之间的严格比较$k$，而不是价值观本身。 逻辑取决于搜索是否会在索引空间中向左或向右移动，而正确性条件取决于该中点处的值是否遵循相对于的不等式$k$。 

答案会累积每个违反的中点决策，因为每个此类违规都必须通过在所选集合中包含该索引来修复。 

## 工作示例

 考虑一个简单的排列：```

```询问$[1, 4, 4]$。 这里$pos(4) = 3$。

 答案又是0。 

现在一个更有趣的案例：```
p = [4, 3, 2, 1, 5]
```询问$[1, 4, 2]$,$pos(2)=3$。 

| 步骤| 中| p[中] | 所需移动| 问题 |

这些示例表明，只有不匹配的中点才会起作用，并且只有当该中点处的值会将搜索发送到错误的方向时。

 ## 边缘情况

 一个关键的边缘情况是当二分搜索中点围绕位置重复振荡时$k$，特别是在反向或对抗性排列中。 在这种情况下，每个中点决策往往与所需的方向相矛盾，并且答案与二叉搜索树的深度而不是段大小成正比。 

另一个重要的情况是当$k$接近区间的一个边界。 二分搜索路径变得高度倾斜，并且只访问了少量的中点。 该算法仍然只正确地计算那些访问过的中点，而不是整个区间，因为一旦达到目标索引，模拟就会停止。 

最后，当段大小为 1 时，算法立即成功或失败，具体取决于该单个位置是否包含$k$，并且无法进行任何修改，这与二分搜索终止的定义相匹配。
