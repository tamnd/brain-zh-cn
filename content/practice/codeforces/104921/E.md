 ## 解决方案
 ## 问题理解

 我们从一个整数开始，两个玩家交替修改它。 玩家每次移动都可以将当前值增加或减少 1。 万尼亚先动。 如果在 Vanya 移动之后，结果立即能被 3 整除，则游戏提前结束。如果在总共 10 步之内没有出现这样的时刻，则 Vova 被宣布为获胜者。 

关键在于，只有万尼亚才能直接获胜，而且只能靠他自己的动作。 Vova 的角色纯粹是防御性的：他试图避免让 Vanya 在 Vanya 轮到后立即落在 3 的倍数上，同时还能生存足够长的时间，直到 10 步限制到期。 

约束很小：最多 100 个测试用例，初始值最多 1000 个。这立即排除了对大型状态空间或优化结构进行大量模拟的需要。 即使是简单的博弈树探索原则上也是可行的，因为深度仅限于 10 步，但我们会发现即使这样也太过分了。 

一个微妙的点是，只有在 Vanya 走棋之后才会检查获胜条件。 Vova 从来不会通过达到整除性来直接获胜，他只能通过阻止 Vanya 的成功直到达到移动限制来获胜。 这种不对称性正是解决方案的驱动力。 

一个幼稚的错误是将游戏视为对称的或在每次移动后检查整除性。 例如，从n = 1开始，如果Vanya玩+1，我们得到2，它不能被3整除。如果一个人错误地检查了两个玩家，人们可能会认为Vova也有获胜条件，这是错误的。 

另一个常见的陷阱是贪婪地模拟，总是试图向 3 的倍数移动。这会失败，因为 Vova 积极干扰，而问题本质上是对抗性的。 

## 方法

 直接的暴力方法会将游戏模拟为深度有限的搜索树。 每个状态由当前数字、移动索引以及轮到谁组成。 从每个状态，我们分为两种可能性，增加或减少一种。 如果我们到达 Vanya 刚刚移动的状态并且数字可以被 3 整除，或者移动次数超过 10 次，我们就会停止。 

这种蛮力之所以有效，是因为状态空间很小：10 次移动中每次移动最多有 2 个选择，最多给出 2^10 = 1024 条路径。 如果有 100 个测试用例，大约有 100,000 个状态，这仍然是可以管理的。 

然而，这是不必要的，因为问题的结构分解为模算术。 每次移动都会使数字改变 ±1，因此只有模 3 的余数才重要。 每一步都会以可预测的方式翻转残基：对于任何残基，Vanya 总是可以强制进行转换，而 Vova 只能通过将其移开来做出反应。 

关键的观察是，唯一重要的是 Vanya 能否在 10 步内将残数强制为 0。 由于两个玩家总是将数字改变±1，因此余数以受控方式循环通过0、1、2。 这将游戏变成了一个有限的周期性状态问题，而不是一个不断增长的数字问题。 

如果我们尝试 10 步的所有可能性，我们很快就会看到一个模式：只要初始值尚未受到 Vova 响应模式的保护，Vanya 就可以立即获胜。 事实上，最佳游戏简化为简单的奇偶/模条件而不是搜索。

 ## 算法演练

 中心思想是仅跟踪模 3 的值并推理 Vanya 如何强制获胜。

1. 计算余数 r = n mod 3。这是影响 Vanya 走棋后我们能否达到 3 的倍数的唯一信息。 
2. 观察 Vanya 移动后，他希望结果值为 0 mod 3。这意味着他希望在某一回合中恰好落在与 0 mod 3 全等的数字上。 
3. 每次移动都会以 +1 或 -1 模 3 改变残数。这意味着每次移动只是在 {0, 1, 2} 之间旋转残数。 
4. 由于玩家交替，每当 Vanya 试图单步接近残数时，Vova 总是可以响应将残数推离 0，但他无法在多次强制交替中永久避免它。 
5. 游戏时间较短，最多 10 步。 在如此小的范围内，Vanya 实际上有足够的机会来迫使 Vova 的响应无法避免 Vanya 回合中的 0 残留，除非初始配置已经处于受保护的循环中。 
6. 结果分析归结为检查 n % 3 == 0 是否立即获胜，或者 Vanya 是否可以在他的第一步或短暂的强制序列后进入 3 的倍数。 在最佳游戏下，这总是会得出确定性结果，该结果仅取决于初始残差模式和移动奇偶性，而不取决于 n 的实际大小。 

事实上，最优结果进一步简化：当且仅当 n % 3 != 0 时，Vanya 获胜。 

### 为什么它有效

 不变量是游戏状态完全减少到模 3 的余数，并且每个玩家只能将该余数沿任一方向旋转一步。 因为 Vanya 首先移动，并且只需要在自己的移动中成功一次，任何非零余数都允许他选择立即达到 0 模 3 的方向，或者迫使 Vova 进入一个他无法在 10 次移动的有限范围内阻止它的位置。 由于状态空间的大小为 3 并且两名玩家都有对称的移动能力，因此 Vanya 唯一稳定的失败配置是当他已经处于残数 0 并且在不给予 Vova 控制权的情况下无法在第一步中改善他的位置时。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        if n % 3 == 0:
            print("Second")
        else:
            print("First")

if __name__ == "__main__":
    solve()
```代码读取每个测试用例并计算 n 模 3 的余数。如果该数字已经可以被 3 整除，则 Vanya 被迫进入任何移动都会打破条件的位置，并且 Vova 可以保持控制足够长的时间，直到 10 步限制到期。 否则，Vanya 可以在第一步立即调整数值，使其达到 3 的倍数。 

故意将实现最小化，因为所有游戏动态都崩溃到这个单一的模块化检查中。

这些例子证明了这种不对称性：只有非 3 的倍数才能赋予 Vanya 直接的强制力。

 ## 边缘情况

 对于 n = 3，我们已经从 3 的倍数开始。Vanya 的第一步必须将值更改为 2 或 4，且不能被 3 整除。从那时起，Vova 可以镜像移动以避免让 Vanya 在他的回合中落在 3 的倍数上，并且 10 步限制保证了 Vanya 无法强行突破。 

当 n = 1 时，Vanya 可以立即移动到 2，它不能被 3 整除，但如果 Vova 没有完全反击，下一回合的补充移动允许他在稍后的 Vanya 回合中达到 3。 由于 Vanya 首先移动并且可以灵活地选择 ±1，因此他可以在少量步内自行移动，从而引导残差循环达到 0。 

对于 n = 1000，残数为 1，其行为与任何其他非零残数相同。 大小无关紧要，仅模块周期就决定了万尼亚能否强行获胜。 

这些案例证实，只有在开始时能被 3 整除，才能在最佳发挥下为 Vanya 创造一个稳定的失败配置。
