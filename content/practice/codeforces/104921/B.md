 ## 解决方案
 ## 问题理解

 我们得到了一小部分个位数的数字。 对于每个测试用例，我们可以精确地选择这些数字中的一个并将其加一。 进行一次更改后，我们将集合中的所有数字相乘，并希望该乘积尽可能大。 

输入的结构很重要：每个测试用例都是独立的，每个测试用例最多包含九个数字。 每个测试用例的输出只是一个整数，这是应用单个允许增量后可能的最佳结果。 

对 n 的约束非常小。 对于 n 最多 9 个和最多 10^4 个测试用例，即使是尝试每种可能的选择来增加哪个数字的解决方案也很容易足够快。 这立即排除了除直接模拟之外的任何复杂预处理或数学优化的需要。 

主要的微妙之处来自于零。 天真的直觉可能表明增加最大数字总是最佳的，但只要存在零，这种方法就会失败。 零使整个乘积为零，因此获得非零结果的唯一方法是将至少一个零转换为一。 例如，用数字`[0, 5, 6]`，将 6 增加到 7 仍然会使乘积为零，而将 0 增加到 1 会使乘积`1 * 5 * 6 = 30`，这绝对更好。 

另一种边缘情况是除 1 之外所有数字均为零。 例如`[0, 0, 9]`。 将 9 增加到 10 产生产品`0`，同时增加零给出`[1, 0, 9]`，仍然是产品`0`。 在这种情况下，每一步都是等效的，但暴力评估仍然可以正确处理它。 

最后一个微妙的情况是所有数字都非零且相对较大。 增加较小的数字有时会优于增加最大的数字，因为乘法对分布很敏感。 例如`[3, 3, 3]`：增加1 3至4的产量`36`，虽然增加任何其他也会产生相同的结果，但一般来说混合分布需要检查所有位置。 

## 方法

 蛮力的想法很简单：尝试每个索引，暂时将该数字加一，计算所有元素的乘积，并保留最大结果。 每次评估都需要 O(n) 次乘法，并且有 n 个选择，因此每个测试用例的成本为 O(n²)。 由于 n 最多为 9，因此实际上这实际上是常数时间，但仍然有助于简化。 

关键的观察结果是决策空间很小。 只有n种可能的走法，并且每一步都是独立的。 不需要动态规划或贪心推理，因为我们不做多个决策，只选择一个位置进行修改。 这将问题分解为直接枚举。 

因此，优化不是为了降低渐近复杂性，而是为了编写最干净的评估循环：计算每个候选索引的乘积并跟踪最大值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(t·n²) | O(t · n²) | O(1) | O(1) | 已接受 |
 | 最优枚举| O(t·n²) | O(t · n²) | O(1) | O(1) | 已接受 |

 实际上，两者是相同的，因为 n 以 9 为界。 

## 算法演练

 我们独立处理每个测试用例并评估所有可能的单个增量。 

1. 读取当前测试用例的数字数组。 我们将其存储为列表，以便我们可以轻松模拟修改。 
2. 初始化变量`best`为零。 这将跟踪在所有要增加的数字选择中看到的最大乘积。 
3. 对于每个索引`i`在数组中，模拟增加`a[i]`一个。 我们不会永久修改数组； 相反，我们将其视为`a[i] + 1`仅用于此计算。 这避免了试验之间的意外遗留效应。 
4. 计算此修改下所有元素的乘积。 每个元素除了`i`保持不变，而位置`i`贡献`(a[i] + 1)`而不是`a[i]`。 
5.将该产品与`best`并更新`best`如果它更大。 这确保了在考虑所有选择后，我们保留最佳的一个。 
6. 输出`best`所有指标都测试完毕后。 

### 为什么它有效

 该算法显式评估问题允许的每个有效操作：恰好选择一个要递增的索引。 每次评估都会计算精确的结果产品，因此不涉及近似或启发式。 由于可能结果的集合正是这 n 个修改的集合，因此对所有结果取最大值可以保证正确性。 选择之间没有交互，因此独立枚举它们可以覆盖整个解决方案空间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        best = 0

        for i in range(n):
            prod = 1
            for j in range(n):
                if i == j:
                    prod *= (a[j] + 1)
                else:
                    prod *= a[j]
            best = max(best, prod)

        print(best)

if __name__ == "__main__":
    solve()
```该实现直接反映了算法。 外循环处理测试用例，内循环处理`i`选择要递增的数字。 第二个内部循环计算该选择的乘积。 

一个常见的实现陷阱是就地修改数组并忘记恢复它，这会导致迭代中级联错误结果。 这里，值`(a[j] + 1)`是动态计算的，完全避免了突变。 

另一个微妙的点是初始化`best`为零而不是原始数组的乘积。 由于增加零可以产生严格更好的结果，因此从零开始可以安全地覆盖所有情况，无需特殊处理。

 ## 边缘情况

 一个关键的边缘情况是数组包含零时。 例如，输入`[0, 2, 3, 4]`除非零增加，否则产生零乘积。 该算法正确评估索引 0 递增的情况，产生`[1, 2, 3, 4]`和产品`24`，它支配着所有其他仍包含零的选择。 

另一种情况是单元素数组`[0]`。 唯一的举措是增加它，产生`[1]`，所以输出是`1`。 该算法自然地处理这个问题，因为它仍然评估唯一的索引并计算`(0 + 1)`。 

当所有数字都很大时，例如`[9, 9, 9]`，增量产生`10`，产品就变成了`900`。 该算法正确地处理了这个问题，而无需处理`10`特别是，因为 Python 中的整数乘法自然支持它。 

最后，当存在多个零时，例如`[0, 0, 5]`，任何单个增量仍至少留下一个零，因此大多数结果为零，除非增量为零。 该算法仍然统一比较所有情况并选择正确的最佳值，而不需要特殊情况逻辑。
