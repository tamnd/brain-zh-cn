 ## 解决方案
 ## 问题理解

 我们正在使用标记为 0 到 9 的圆形键盘。您首先将光标定位在数字 1 上，您的任务是键入固定的 4 位 PIN。 您可以随时按光标下的当前数字，或将光标移动到圆圈上的相邻数字。 从数字 x 开始移动意味着您可以转到 x−1 或 x+1，并进行环绕，以便 0 与 9 相邻。 

每一次移动或按下都只花费一秒钟。 目标是最小化从位置 1 开始生成给定 4 位序列所需的总时间。 

重要的结构是，该问题本质上是非常小的状态空间上的最短路径计算。 每个状态都由您当前的数字位置定义，并且转换要么是停留并按下，要么是沿着大小为 10 的循环移动。 

尽管测试用例的输入大小很大，但每个测试用例的结构大小都是恒定的。 这立即排除了任何依赖于每种情况超过 O(1) 或 O(10) 工作的算法。 任何涉及长字符串模拟或全局预处理的事情都是不必要的。 

微妙的边缘情况来自环绕距离。 例如，从 0 移动到 9 需要 1 秒，而不是 9 秒。使用绝对差值的简单实现在输入 0000 或 9090 时会失败，在这些输入中，最佳移动总是回绕。 

另一个边缘情况是忘记光标始终从 1 开始。假设从 PIN 的第一个数字开始的解决方案在像 9999 这样的情况下会失败，在这种情况下，起始成本是不小的。 

## 方法

 强力解释将模拟所有可能的移动和按压序列。 从每个数字，我们可以分为向左移动、向右移动或按下。 由于每个 PIN 的长度为 4，因此原则上对状态（PIN 中的位置、索引）进行简单的 BFS 仍然是可行的，但这是矫枉过正且不必要的。 

更重要的是，我们实际上不需要考虑所有中间运动序列。 关键的观察结果是，强制按下一个数字四次，并且在连续按下之间，我们只需沿着 10 个节点的循环将光标从当前数字移动到下一个所需的数字。 

因此，问题分解为固定图中连续数字之间的独立最短路径。 每个转换成本只是大小为 10 的循环上的最短距离。这将整个问题简化为对四个转换成本求和：从初始位置 1 到第一位数字，然后在连续数字之间。 

暴力破解会失败，因为它将运动视为一系列选择，而该结构保证了任意两个数字之间的最佳运动是由周期上较短的弧线唯一确定的。

 ## 算法演练

 我们将问题简化为计算循环数轴上数字之间移动的成本。

1. 从光标位于数字 1 处开始。这是采取任何操作之前的初始状态，它很重要，因为第一次移动取决于它。 
2. 对于 PIN 的第一位数字，计算从 1 到该数字的最小圆形距离。 在 0-9 环上，这是 min(|a−b|, 10−|a−b|)。 这代表按下按钮之前所需的最佳移动次数。 
3. 到达第一个数字后，按该数字增加 1 秒。 此压力是强制性的，不能与动作合并。 
4. 将当前光标位置更新为第一位。 这确保了从新状态正确计算后续转换。 
5. 对于 PIN 中的下一个数字，计算从当前数字到目标数字的相同圆形距离，增加 1 秒的按下时间，并更新当前位置。 
6. 将所有移动和冲压成本累积到测试用例的运行总计中。 

每个步骤背后的原因是，移动和按压是独立的动作，并且两个固定数字之间的移动总是折叠成循环图上的最短路径。 

### 为什么它有效

 在任何时刻，系统的状态都由当前数字完整描述。 下一个所需的数字由输入确定。 它们之间的转换是具有均匀边权重的循环图上的最短路径问题。 在这样的图中，两个节点之间的最佳路径始终是围绕循环的两条弧线之一，因此考虑中间绕道或重新访问节点没有任何好处。 这保证了两两最短距离的求和与全局最优动作序列完全匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def dist(a, b):
    d = abs(a - b)
    return min(d, 10 - d)

t = int(input())
for _ in range(t):
    s = input().strip()
    cur = 1
    ans = 0

    for ch in s:
        x = ord(ch) - 48
        ans += dist(cur, x) + 1
        cur = x

    print(ans)
```功能`dist`对数字环上的圆距离进行编码。 关键细节是使用的环绕计算`10 - d`，它可以正确处理 0 到 9 等转换。 

主循环保持不变式`cur`始终是处理下一个字符之前光标当前所在的数字。 对于每个数字，我们添加移动成本加上一次按下操作，然后更新状态。 

一个常见的实现错误是忘记正确地将字符转换为整数或使用线性距离而不是圆形距离。 在环绕大量的情况下，两者都会导致错误的答案。

import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    t = int(input())
    for _ in range(t):
        s = input().strip()
        cur = 1
        ans = 0
        for ch in s:
            x = ord(ch) - 48
            d = abs(cur - x)
            ans += min(d, 10 - d) + 1
            cur = x
        print(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as _io
    out = _io.StringIO()
    with redirect_stdout(out):
        solve()
    sys.stdin = old_stdin
    return out.getvalue().strip()

 ## 边缘情况

 最脆弱的情况是 0 到 9 之间的环绕。对于输入`9000`，从 1 开始，正确的第一步不是 8 步，而是 2 步，通过 1→0→9 或 1→0，具体取决于方向选择。 该算法通过始终采用`min(|a-b|, 10-|a-b|)`，它会自动选择较短的圆弧。 

为了`0000`，光标从 1 开始。第一次转换是 1 到 0，这通过环绕花费 1 步而不是 9 步。该算法计算`min(1, 9) = 1`，因此总成本变为 1 + 1 + 1 + 1 + 1 = 5，匹配最优序列。 

为了`9999`，从 1 开始，第一个移动是 1 到 9，通过环绕花费 2，而不是 8。后续的每次转换都是 9 到 9，花费 0 移动加上按压，因此总数在第一步之后正确稳定。
