 ## 解决方案
 ## 问题理解

 我们得到了几个独立的 8 × 8 字符网格。 每个网格大部分都充满了点，但其中的某个地方隐藏着一个单词。 该单词直接写在一列中，占据连续的行而不会中断。 网格中的每个其他单元格都是一个点。 

每个网格的任务是通过从上到下读取正确列中的字母来恢复隐藏的垂直单词。 

约束很小而且是固定的。 每个测试用例恰好包含 64 个字符，排列在 8 x 8 块中，并且最多有 1000 个这样的测试用例。 这意味着总输入大小约为 64,000 个字符，因此任何扫描每个网格恒定次数的方法都足够快。 即使每个测试用例重复进行完整扫描仍然是可以接受的，但没有必要。 

就性能而言，不存在真正的算法边缘情况，但在解释布局时存在正确性陷阱。 一个天真的错误是假设单词可能是分散的或者需要将多个列拼接在一起。 另一个错误是尝试按行读取或在遇到的第一个字母处停止，而不确保保持在同一列内。 

例如，考虑一个网格，其中单词是`"lost"`在一栏中：```
........
....l...
....o...
....s...
....t...
........
........
........
```正确的输出是`"lost"`。 有缺陷的方法可能会逐行扫描并在出现的地方挑选字母，这在这里仍然有效，但如果多个列包含类似风格的其他问题中的字母，则会失败。 定义约束是恰好有一列包含单词的所有字母。 

另一种边缘情况是当单词是单个字符时，例如：```
........
........
....a...
........
........
........
........
........
```输出必须是`"a"`。 任何假设至少两个字母或尝试检测开始和结束标记的逻辑都可能在此处中断。 

关键的结构事实是，恰好有一列包含非点字符，并且这些字符从上到下连续出现。 

## 方法

 强力解释是检查每一列并检查它是否包含任何字母。 对于每一列，我们可以扫描所有 8 行并收集不是点的字符。 如果结果列表非空，则该列包含该单词，我们将其输出。 

由于网格大小固定为 8 x 8，因此即使尝试每个可能的列并扫描每一行的方法实际上也是恒定时间。 每个测试用例最坏的情况是 64 个单元检查，而对于多达 1000 个测试用例，这只是 64,000 次操作，这很简单。 

更直接的观察是，我们根本不需要“搜索”。 由于该单词完全位于一列中，因此每一行总共最多包含一个非点字符，并且所有这些字符都属于同一列。 因此，我们可以简单地逐行扫描，提取每行的第一个非点字符（如果存在），然后将它们连接起来。 这直接按顺序重构了单词。 

暴力破解之所以有效，是因为它明确地验证了每一列。 优化的方法通过利用唯一性保证消除了对列选择的需要：只有一列可以包含字母，因此任何按行提取都会自动保持一致。

 ## 算法演练

 1.读取测试用例数量`t`，因为每个网格都是独立的，必须单独处理。 
2. 对于每个测试用例，读取代表网格 8 行的 8 个字符串。 每个字符串的长度为8，因此我们可以将其视为固定的字符数组。 
3. 初始化一个空列表（或字符串构建器）来累积隐藏单词的字符。 
4. 迭代 8 行中的每一行。 对于给定的行，从左到右扫描它的 8 列，直到找到不是的字符`'.'`。 

当我们找到这样的字符时，将其附加到答案中并立即移至下一行。 我们不会继续扫描该行，因为每一行最多包含一个构造上的相关字符。 
5. 处理完所有8行后，输出累积的字符串。 

重要的设计选择是扫描每行，而不是首先尝试识别列。 由于单词是垂直对齐的，因此每一行仅贡献同一列中的一个字符，因此逐行提取会自动保留顺序。 

### 为什么它有效

 每个网格恰好包含一列包含字母的列，并且在该列中，字母出现在形成单词的连续行中。 所有其他单元格都是点。 因此，每一行包含零个字母或恰好一个字母，并且所有非空行对应于相同的列索引。 通过从每行中提取第一个非点字符，我们按从上到下的顺序重建字母序列。 没有其他专栏可以贡献一封信，因此不会出现歧义。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        grid = [input().strip() for _ in range(8)]
        word = []

        for r in range(8):
            for c in range(8):
                if grid[r][c] != '.':
                    word.append(grid[r][c])
                    break

        out.append("".join(word))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现直接遵循逐行提取策略。 对于每一行，它从左到右扫描并在第一个非点字符处停止。 这`break`是必不可少的，因为每一行最多贡献一个字符，继续下去是多余的。 

使用`strip()`确保我们不会意外地在网格表示中包含换行符。 最终答案会累积在列表中并立即打印，以避免重复的 I/O 开销。

 ## 边缘情况

 处理单字符单词是因为逐行扫描仍然准确地找到一个整体非点单元。 对于仅存在一个字母的输入，例如：```
........
........
........
....x...
........
........
........
........
```该算法访问每一行，仅附加`"x"`，并产生`"x"`根据需要。 

位于最后一列的单词的处理无需任何特殊逻辑。 例如：```
.......k
.......i
.......t
.......e
.......n
.......s
.......u
.......n
```每行扫描都会到达第 7 列并在那里找到该字母。 排序仍然正确，因为行是从上到下处理的，保留了垂直顺序。 

单词外部有许多点的网格不会影响正确性，因为内部循环在每行的第一个非点字符处停止。 即使未来的变体在其他地方有噪音字符，只有一列包含字母的不变性也确保了不会出现错误的提取。
