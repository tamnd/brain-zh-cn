 ## 解决方案
 ## 问题理解

 我们得到一排煎饼，每个煎饼要么快乐的一面朝上，要么空白的一面朝上。 我们还有一个翻转器，它总是精确地翻转 K 个连续的煎饼。 翻转会反转该段中每个煎饼的状态。 

任务是确定使每个煎饼正面朝上所需的最少翻转次数，或者确定这是不可能的。 

关键的限制是每次翻转都会影响固定长度的窗口，因此决策是局部的，但会产生长期后果。 一旦应用翻转，它就会永久改变该段中所有 K 个煎饼的状态，并且以后的操作无法撤消其效果，除非通过进一步翻转。 

每个测试用例的输入大小最多为 1000 个煎饼，因此任何尝试所有翻转序列的解决方案都是不可行的。 对翻转位置的强力搜索将呈指数级增长，因为在每个位置我们都可以选择翻转或不翻转，从而大致导致$2^N$的可能性。 

当所需的翻转超出字符串末端时，就会出现微妙的边缘情况。 例如，如果最后几张煎饼是空白的，并且剩余的位置少于 K 个，则无法修复它们，因为没有有效的翻转可以覆盖它们。 这就是许多天真的贪婪尝试如果不显式检查边界就会失败的地方。 

## 方法

 暴力策略将尝试有效翻转位置的所有子集并模拟每个序列的效果。 每次模拟的成本为 O(N)，并且有 O(N) 个可能的翻转位置，因此总搜索空间是指数级的。 即使 N 约为 20，这也很快变得不可行。 

问题的结构表明了一种更直接的策略。 当从左到右扫描时，一旦我们决定是否在位置i翻转，我们就完全确定了煎饼i在接下来的过程中的状态。 任何影响 i 的后续翻转都必须在 i 处或之后开始，这是不可能的，因为我们从左到右处理并且永远不会重新访问之前的位置。 

这创建了一个强大的贪婪结构：在每个位置，如果当前错误，我们就被迫立即修复它。 唯一的额外复杂性是有效跟踪先前的翻转是否影响当前索引。 这可以通过维持影响当前位置的翻转的运行奇偶性来处理。 

一旦我们采用这个观点，解决方案就会简化为单通道模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^N·N) | O(2^N·N) | O(N) | 太慢了|
 | 贪心模拟| O(N) | O(N) 或 O(1) | 已接受 |

 ## 算法演练

 我们从左到右处理字符串，同时跟踪每个位置当前翻转的次数是偶数还是奇数。 

1. 我们维护一个滑动指示器，告诉我们当前煎饼是否被翻转了奇数次。 这使我们能够计算其有效状态，而无需重复物理修改字符串。 
2. 对于从左到右的每个索引 i，我们在考虑之前的翻转后计算煎饼的实际可见状态。 如果它已经很高兴，我们什么也不做并继续。 
3.如果当前的煎饼是空白的，我们必须从i开始翻转，因为后面的操作不能影响位置i而不影响之前的位置，这些位置已经固定了。 
4. 在位置 i 进行翻转之前，我们检查 i + K 是否超过字符串的长度。 如果是这样，我们立即得出结论：该配置是不可能的。 
5. 当我们应用翻转时，我们使用差异数组或通过在 i 和 i + K 处切换正在运行的翻转状态来记录其效果。这确保我们稍后可以在 O(1) 中确定对未来位置的影响。 
6. 我们继续这个过程直到字符串末尾，累积执行的翻转次数。 

### 为什么它有效

 在每一步 i 中，所有影响严格小于 i 的索引的决策都已经固定，并且永远不会再改变。 在 i 之后开始的任何翻转都不能影响位置 i。 因此，如果位置 i 在当前累积的翻转奇偶校验下不正确，唯一可能的纠正就是在 i 处开始翻转。 这使得每个位置的选择都是强制的而不是可选的，这保证了贪婪构造（如果可能）以最少的操作生成有效的序列。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(S, K):
    n = len(S)
    diff = [0] * (n + 1)
    flip = 0
    res = 0

    for i in range(n):
        flip ^= diff[i]
        cur = S[i]

        if flip:
            cur = '+' if cur == '-' else '-'

        if cur == '-':
            if i + K > n:
                return "IMPOSSIBLE"
            res += 1
            flip ^= 1
            diff[i + K] ^= 1

    return str(res)

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        parts = input().split()
        S = parts[0]
        K = int(parts[1])
        ans = solve_case(S, K)
        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    solve()
```该解决方案维护一个差异数组来表示滑动窗口上的主动翻转。 每次我们开始翻转时，我们都会在开始时切换效果并在 K 个位置后取消它，因此未来的索引会自动继承正确的奇偶校验。 

关键的实现细节是在应用当前翻转奇偶校验后计算有效字符，然后决定是否需要新的翻转。 这可以避免物理上改变字符串。

import sys, io

def run(inp: str) -> str:

    return solve(inp)

def solve(inp=None):
    data = sys.stdin.read().strip().split()
    T = int(data[0])
    idx = 1
    out = []
    for tc in range(1, T + 1):
        S = data[idx]
        K = int(data[idx + 1])
        idx += 2

        n = len(S)
        diff = [0] * (n + 1)
        flip = 0
        res = 0

        for i in range(n):
            flip ^= diff[i]
            cur = S[i]
            if flip:
                cur = '+' if cur == '-' else '-'

            if cur == '-':
                if i + K > n:
                    out.append(f"Case #{tc}: IMPOSSIBLE")
                    break
                res += 1
                flip ^= 1
                diff[i + K] ^= 1
        else:
            out.append(f"Case #{tc}: {res}")

    return "\n".join(out)

 ## 边缘情况

 当 K 等于字符串长度时，唯一可能的操作是翻转整个数组。 如果至少有一个“-”，该算法会正确地执行一次翻转，如果无法解析结构，则返回不可能。 

当最后一个“-”出现在大于n-K的索引处时，没有翻转可以覆盖它。 该算法在到达该索引时立即检测到这一点，确保它以后不会尝试无效操作。 

当字符串已经全部为“+”时，扫描不执行翻转，因为每个位置都已满足零奇偶校验，这表明贪婪规则不会引入不必要的操作。
