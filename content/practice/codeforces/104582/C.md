 ## 解决方案
 ## 问题理解

 我们有一长排摊位，两端都被永久占用，中间有 N 个空摊位。 人们一一进入，每个人根据距两侧最近的占用摊位的距离来选择摊位。 K 个人占据摊位后，我们需要确定第 K 个人所选择的位置“看到”的距离左侧和右侧最近的已占用摊位的空位。 

关键的观察是该过程不是任意的。 在每一步中，占用的隔间将空段分割成独立的间隔。 每个间隔的行为就像同一问题的较小实例：在长度为 L 的块内，下一个人将选择一个位置，以非常具体的确定性方式将其分割。 

这些限制迫使我们采用非模拟方法。 N 可以大到 10^18，因此显式模拟每个人是不可能的。 当 K 很大时，即使维持完整的区间结构并更新 K 次也会失败，因为 K 本身也可以达到 10^18。 唯一可行的方法是推理区间如何大规模演化。 

当多个间隔具有相同的最佳选择大小时，会出现微妙的边缘情况。 例如，当一个区间对称分割时，两个产生的子区间具有相同的结构，并且打破平局规则很重要。 仅存储间隔长度但忽略多重性或顺序的简单模拟在重建首先处理哪个段时将失败。 

另一种边缘情况是当 N 较小而 K 相对于 N 较大时，导致许多间隔的大小变为 0 或 1。 此时，最小和最大距离会崩溃，并且对基本情况的粗心处理会导致不正确的负值或相差一的值。 

## 方法

 暴力方法按顺序模拟每个人。 我们维护一个空段的数据结构，最初是大小为 N 的单个段。每次，我们都会根据规则选择产生最佳选择的段：最大化到边缘的最小距离，然后最大化最大距离，然后选择最左边的。 一旦选择了一个分段，它就会分成两个较小的分段。 

这是有效的，因为每个选择仅取决于当前段，并且分割是局部的。 然而，操作的数量是K，并且每个操作都需要在可能的O(K)个段中选择最佳的段。 这会导致最坏情况下的 O(K^2) 行为，而当 K 达到 10^18 时这是不可能的。 

关键的见解是我们实际上不需要一步一步地模拟订单。 相反，我们观察到长度为 L 的每个段的行为方式始终相同：它产生两个子段，其大小仅取决于 L。所有相同大小的段都是可互换的。 这将过程变成了分段大小的计数问题，而不是对个体的显式模拟。 

我们重复处理最大的可用段大小，计算它出现的次数，并将其分裂传播为具有更新的多重性的两个新大小。 这相当于对段大小的贪婪 BFS，但使用映射或优先级结构批量完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(K^2) | O(K^2) | O(K) | 太慢了|
 | 最佳| O(log N) 到 O(K log N) | O(K) | 已接受 |

 ## 算法演练

 我们根据每个自由区间的长度对其进行建模。 对于长度为 L 的线段，当一个人选择其中的一个摊位时，该线段会分成两部分。 所选择的位置始终是中间的，但是当 L 为偶数时，有两个中间候选者，并且打破平局有利于左侧。 

这导致了确定性的分割大小：

 对于长度为 L 的线段，定义：

 左侧部分 = (L - 1) // 2

 右侧部分 = L // 2

我们维护一个频率图，其中键是段长度，值是当前存在的此类段的数量。 

我们还维护一个始终提取最大可用段的结构，因为更大的段对应于更高优先级的选择。 

## 步骤

 1. 用大小为 N 的单个段初始化 max 结构。 

这代表了在任何人进入之前整个空荡荡的浴室。 
2. 当K大于零时，重复取当前可用的最大段大小L。 

这是有效的，因为贪心规则总是首先选择最大的有效自由区间。 
3. 确定一次可以分配多少人到大小为 L 的分段，即 cnt，此类分段的数量。 

如果K大于cnt，我们一起处理； 否则，我们只处理其中的 K 个。 
4. 根据这个分段大小计算实际占用座位的人数，即 use = min(K, cnt)，并通过 use 减少 K。 

这确保了我们批量处理而不是逐一模拟。 
5. 对于每个已处理的大小为 L 的段，它会分为两个大小为 (L - 1) // 2 和 L // 2 的新段。 

我们将每个结果段的使用副本添加回结构中。 
6. 如果 K 达到零，则最后处理的段大小 L 决定答案。 从 L 计算：

 最大值（LS，RS）= L // 2

 分钟（LS，RS）=（L-1）//2

 ## 为什么它有效

 在任何时候，每个自由段都独立运行，段内的选择仅取决于其长度。 贪婪选择规则总是更喜欢较大的段，因此段处理顺序严格由大小决定，而不是历史记录。 由于所有相同大小的段都是可互换的，因此将它们分组到计数中不会丢失排序信息。 从 L 到它的两个子节点的变换是确定性的，因此系统演化为段大小的多重集，没有歧义。 

## Python 解决方案```python
import sys
import heapq
from collections import defaultdict

input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N, K = map(int, input().split())

        # max heap via negative values
        heap = [-N]
        cnt = defaultdict(int)
        cnt[N] = 1

        while heap:
            L = -heapq.heappop(heap)
            if cnt[L] == 0:
                continue

            c = cnt[L]
            cnt[L] = 0

            if K <= c:
                # answer comes from this segment size
                left = (L - 1) // 2
                right = L // 2
                print(f"Case #{tc}: {right} {left}")
                break

            K -= c

            left = (L - 1) // 2
            right = L // 2

            for nxt in (left, right):
                if nxt > 0:
                    if cnt[nxt] == 0:
                        heapq.heappush(heap, -nxt)
                    cnt[nxt] += c

solve()
```堆确保我们始终首先处理最大的段大小，匹配问题的贪婪结构。 字典跟踪多重性，因此我们可以折叠相同的片段，而不是单独处理它们。 

当 K 落入当前批次的线段时，终止条件恰好发生，这意味着第 K 个人被分配到大小为 L 的线段。从该线段开始，距离完全由其分割结构决定。 

一个常见的实现陷阱是忘记必须一起处理相同大小的多个段。 一一处理它们仍然符合逻辑，但变得太慢。 另一个微妙的问题是计算左右部分：交换它们或对两者使用 L // 2 会破坏正确打破平局所需的不对称性。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(log N) 摊销 | 每个段大小都会处理一次并分成更小的大小 |
 | 空间| O(log N) | 仅存储不同的段大小 |

 不同段大小的数量增长缓慢，因为每次分割大约使间隔减半。 这确保了即使 N 达到 10^18，结构仍然很小，使解决方案保持在限制范围内。

 ## 边缘情况

 对于 N = 1，唯一的段在第一次分割后立即产生两个大小为 0 和 0 的空部分。 该算法处理此问题是因为两个计算出的子项均为零并且在堆中被忽略。 答案直接从初始段确定，产生正确的零距离。 

当 N 为偶数时，假设 N = 6，则分割变为 (5 // 2 = 2, 3)。 该算法始终将右侧指定为 L // 2，左侧指定为 (L - 1) // 2，保留确定性打破平局规则。 这确保了平等中间立场中的左偏选择得到尊重。 

当 K 恰好等于给定大小的段数时，算法恰好在该级别停止，而不会过度消耗段，从而避免了差一错误，否则会将最终的段选择转移到更小的间隔。
