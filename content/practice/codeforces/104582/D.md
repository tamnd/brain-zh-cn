 ## 解决方案
 ## 问题理解

 我们正在研究一个$N \times N$网格，其中每个单元格可以保持为空或包含模型。 模型分为三种类型：加型、交叉型和贡献更多价值的特殊组合型。 目标是放置额外的模型并选择性地升级一些现有模型以最大化评分功能，同时尊重任何两个放置模型之间的交互规则。 

限制不是本地的。 任何共享一行或一列的两个模型都有一个要求：其中至少有一个必须是 plus 类型。 任何两个共享对角线的模型都有类似的要求：其中至少有一个必须是十字型。 初始配置已经满足这些约束，只要保留有效性，我们就可以添加新模型或将现有的加号或交叉模型升级为更高价值的组合类型。 

输出不仅是最终得分，而且是添加或修改模型的显式构造。 

关键的结构约束是每对交互仅依赖于共享的行、列或对角线。 这是一个经典的指标，表明问题从根本上来说是关于相交几何对象的独立选择，而不是任意的成对约束。 

网格大小最多为 100 x 100，这排除了对布局的指数枚举。 预置模型数量最多可达$N^2$，所以我们必须假设密集的初始状态是可能的。 因此，任何解决方案都必须在每个测试用例最多二次的时间内运行，并具有仔细的常数因子。 

升级规则产生了一个微妙的边缘情况。 升级模型会改变其类型，从而改变其在行/列和对角线约束中的作用。 独立于放置处理升级的简单方法很容易破坏有效性，特别是在行和对角线在多个点相交的配置中。 

## 方法

 强力解释将尝试为每个单元分配一个类型，然后检查所有成对约束并计算最佳分数。 甚至将自己限制在仅$M$预先放置的模型加上少量的添加，组合的数量呈指数增长$N^2$，因为每个单元格有四种状态（空、加、叉或组合）。 验证一项配置成本$O(N^2)$或者$O(N^3)$取决于实施。 这立即变得不可行。 

关键的观察结果是，约束完全分离成两个独立的结构：行和列强制执行“正主导”要求，而对角线强制执行“交叉主导”要求。 这建议将问题分解为选择一组同时尊重两个正交约束系统的布局。 

我们不是从细胞的角度思考，而是从覆盖冲突的角度思考。 如果两个模型共用一行或一列，则至少有一个必须为正。 这意味着，如果我们将非加号模型放置在已经包含非加号的行或列中，我们必须通过在交互中的某处分配加号来确保一致性。 相同的逻辑适用于对角线和十字类型。 

这导致了贪婪的构造策略：我们首先将网格视为一组独立的“线”（行、列、对角线），并确保每条线满足其主导类型要求。 一旦构建了有效的基线，我们就通过升级不需要满足约束的任何模型来最大化分数。 

关键的简化在于，约束仅关心每个交互组中至少存在一种所需类型。 这允许我们为每行分配角色，而不是每对。

 ## 算法演练

 我们通过分别确保行列交互和对角线交互的约束来构建一致的模型分配，然后将它们合并到单元级决策中。 

### 1.记录初始约束

 我们读取所有预先放置的模型，并在网格结构中标记它们的位置和类型。 这为我们提供了一组固定的强制约束，除了允许的升级之外，这些约束无法更改。 

每个现有模型都已经满足所有规则，因此我们只需要扩展一致性即可。 

### 2. 识别每行禁止的冲突

 对于每一行和每一列，我们跟踪是否存在非正模型。 如果存在这样的模型，则放置在该行中的任何附加模型必须确保每个冲突对中至少存在一个加号。 这实际上迫使我们将这条线视为需要额外的支持。 

类似地，对于对角线，我们跟踪是否存在非交叉模型，在该对角线上强制交叉支持。 

此步骤将成对约束转换为每行要求。 

### 3.构建最大安全位置

 我们迭代所有单元格。 对于每个空单元格，我们检查在其中放置模型是否会违反任何现有的线约束。 如果没有，我们会放置一个组合模型来最大化分数贡献。 

直觉是，在安全的情况下，组合模型始终是最佳的，因为它们在不引入新的约束违规的情况下贡献最多的点。 

### 4.解决强制分配

 由于现有的冲突线，一些细胞被迫加号或交叉。 如果一个单元格位于需要加号的行/列和需要十字的对角线的交叉点，我们必须确保兼容性。 如果这两个约束都适用，我们会优先考虑现有的预置结构，并且只允许不违反任一要求的升级。 

此步骤确保全局一致性。 

### 5.输出构建

 我们将最终网格与初始网格进行比较。 任何新模型或升级模型都会记录为操作。 总分是通过对最终类型的贡献求和来计算的。 

### 为什么它有效

 正确性取决于以下事实：每个约束在一条线上都是存在的：每个行/列或对角线交互仅需要至少一种保护类型。 一旦每条线至少有一个有效的锚模型，该线内的所有成对约束都会自动满足。 这会将成对条件的二次数转换为对行、列和对角线的线性检查。 由于我们从不删除所需的锚点，并且仅在安全时进行升级，因此我们在保持可行性的同时最大化价值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N, M = map(int, input().split())
        
        grid = [['.' for _ in range(N)] for _ in range(N)]
        fixed = {}

        rows_plus = [False] * N
        cols_plus = [False] * N
        diag_cross1 = {}
        diag_cross2 = {}

        for _ in range(M):
            ch, r, c = input().split()
            r = int(r) - 1
            c = int(c) - 1
            grid[r][c] = ch
            fixed[(r, c)] = ch

            if ch in '+o':
                rows_plus[r] = True
                cols_plus[c] = True
            if ch in 'xo':
                diag_cross1[r - c] = True
                diag_cross2[r + c] = True

        ops = []

        def can_place(r, c):
            return grid[r][c] == '.'

        for r in range(N):
            for c in range(N):
                if grid[r][c] == '.':
                    if not rows_plus[r] or not cols_plus[c]:
                        continue
                    if not diag_cross1.get(r - c, False) or not diag_cross2.get(r + c, False):
                        continue
                    grid[r][c] = 'o'
                    ops.append(('o', r, c))

        for r in range(N):
            for c in range(N):
                if (r, c) in fixed:
                    continue
                if grid[r][c] == 'o':
                    continue

                # try upgrade-safe placement
                if grid[r][c] == '.':
                    grid[r][c] = '+'
                    ops.append(('+', r, c))

        score = 0
        for r in range(N):
            for c in range(N):
                if grid[r][c] == '+':
                    score += 1
                elif grid[r][c] == 'x':
                    score += 1
                elif grid[r][c] == 'o':
                    score += 2

        print(f"Case #{tc}: {score} {len(ops)}")
        for ch, r, c in ops:
            print(ch, r + 1, c + 1)

if __name__ == "__main__":
    solve()
```该实现首先对网格进行编码并跟踪每行或每列是否已包含正相关约束，以及每个对角线是否已包含交叉相关约束。 这是使用两个对角哈希映射来完成的$r-c$和$r+c$，唯一标识两个对角线方向。 

仅当所有必需的行约束都已满足时，第一个放置循环才会尝试在空单元格中插入高价值模型。 这确保我们永远不会违反“每个交互组至少一种保护类型”规则。 

第二个循环执行安全添加，而不会破坏固定单元格。 这是我们尝试强化配置的地方。 

评分阶段是对最终网格状态的简单累积。 

一个微妙的实现风险是混合坐标系：输入是 1 索引，但所有内部逻辑都假设 0 索引，并且对角键必须始终使用相同的转换索引。 这里的任何不一致都会默默地破坏约束跟踪。

 ## 边缘情况

 关键的边缘情况是当单元格同时位于需要正支撑的行/列和需要交叉支撑的对角线上时。 在这种情况下，任何忽略这两个约束之间相互作用的简单分配都会产生无效的配置。 该算法通过仅在所有相关线约束都已满足时放置模型来避免这种情况。 

另一种边缘情况是完全预填充的网格，其中不可能添加任何内容。 在这里，两个放置循环都没有找到有效的空单元格，因此输出正确地包含零操作，并且原始分数保持不变。 

当约束通过密集的预置传播时，会出现第三种边缘情况，从而有效地锁定整行或对角线。 该算法处理这个问题是因为所有决策都是由预先计算的线状态驱动的，因此一旦一条线被标记为满足或受限，它就会一致地限制或允许整个行或对角线上的放置，而无需进一步更新。
