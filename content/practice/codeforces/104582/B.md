 ## 解决方案
 ## 问题理解

 我们收到了几个独立的查询。 每个查询提供一个正整数$N$。 想象一下我们从 1 向上数到$N$，对于每个数字，我们检查从左到右读取时其小数位数是否永远不会减少。 像 123、7、224488 这样的数字是可以接受的，因为当我们扫描时，数字永远不会下降。 像 321 或 495 这样的数字是不可接受的，因为某个数字比前一个数字小。 

对于每个$N$，我们想要范围内的最大数字$[1, N]$满足这个单调数字属性。 

输入大小最多允许 100 个查询，每个查询$N$可以大到$10^{18}$。 这立即排除了任何检查从 1 到$N$，因为单个测试用例可能需要多达$10^{18}$检查，即使使用极快的每个号码验证，这也远远超出了可行的限制。 

一个微妙的边缘情况来自于“几乎整洁”但在数字后期失败的数字。 例如，如果$N = 332$，一个朴素的减量$N$可能会产生 331 或 330 等候选项，但粗心的数字处理可能会跳过 329 或 299 等有效答案，具体取决于纠正的实施方式。 另一种失败情况发生在重复数字周围，例如$N = 11110$，其中最佳答案是 1119，天真的贪婪修复可能会意外保留无效的尾随结构。 

关键困难在于约束不是位置算术，而是全局数字单调性约束。 

## 方法

 暴力解决方案将从$N$然后向下检查每个整数，看看它的数字是否是非递减的。 检查一个数字是$O(d)$在哪里$d \le 18$，因此在最坏的情况下，我们可能会检查所有数字直至正确答案。 在最坏的情况下，比如$N = 10^{18}$，第一个整齐的数字相对于$N$，这意味着我们可以扫描数轴的巨大后缀。 这是完全不可行的。 

从结构上观察，整洁数具有严格的数字形式：一旦某个数字在某个位置减少，右边的所有数字都可以用 9 替换，而不会破坏最大值条件，因为 9 是最大的数字，只要将其放在较小或相等的数字后面，就保持非递减顺序。 这表明我们不需要搜索空间； 相反，我们可以从左到右或从右到左本地纠正数字。 

更精确的观点是从左到右扫描时数字顺序中断的第一个位置来思考。 此时，前缀必须向下调整，并且其之后的所有内容在约束下都变得最大化。 重复此修复会产生一个保证整洁且最大可能不超过的最终数字$N$。 

这将问题从整数搜索转变为数字上的单个线性传递，并偶尔进行向后修正。

 ## 算法演练

 我们将数字视为可变的数字列表。 

1. 转换$N$到一个数字数组中。 这允许直接操作位置而不是算术重建。 
2.从左到右扫描，找到第一个数字严格递减的索引，意思是$digits[i] < digits[i-1]$。 这是第一次违反整洁，之前的一切仍然有效。 
3、发现岗位违规行为时$i$，我们减少位置上的数字$i-1$1 并将该位置标记为“校正点”。 这是必要的，因为保留原始数字将保留强制无效排序的前缀。 
4. 减少校正点后，必须保证前缀保持不减少。 这可能会导致连锁反应，因为减少一个数字可能会违反其前一个数字的条件。 因此，我们从修正点向左移动，修复任何新创建的反转。 
5. 纠正前缀后，我们将纠正点右侧的所有数字设置为 9。这在保持有效性的同时最大化了数字，因为 9 是最大的数字，并且在有效前缀之后不会引入新的递减对。 
6. 完成修复后，我们可能引入了前导零（例如，当类似 1000 的结构变成 0999 时）。 我们删除前导零以恢复有效的整数表示。 
7. 得到的数字就是该测试用例的答案。 

关键思想是，每次我们检测到违规行为时，我们都会将数字向下推到足以恢复单调性，然后贪婪地将所有内容最大化到右侧。 

### 为什么它有效

 在每一步中，我们都保持不变，即直到当前校正点的前缀是最大可能的前缀，不超过原始数量，并且仍然可以扩展为整齐的数字。 任何时候发生违规时，保持当前数字不变都会迫使后面的数字小于它，这在整洁的数字中是不可能的。 因此，唯一有效的修复是减少前一位并将后缀重置为单调约束下的最大可能值，即全是9。 由于更正仅向左移动并且从不增加数字，因此我们收敛到字典顺序上最大的有效数字不超过$N$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_one(n_str: str) -> str:
    digits = list(map(int, n_str.strip()))
    n = len(digits)

    # find first violation
    mark = n
    for i in range(n - 1, 0, -1):
        if digits[i] < digits[i - 1]:
            digits[i - 1] -= 1
            mark = i

    # fix potential cascading violations to the left
    for i in range(mark - 1, 0, -1):
        if digits[i] < digits[i - 1]:
            digits[i - 1] -= 1
            mark = i

    # set suffix to 9
    for i in range(mark, n):
        digits[i] = 9

    # handle leading zeros
    i = 0
    while i < len(digits) and digits[i] == 0:
        i += 1

    return ''.join(map(str, digits[i:])) if i < len(digits) else "0"

def main():
    t = int(input())
    for tc in range(1, t + 1):
        n = input().strip()
        print(f"Case #{tc}: {solve_one(n)}")

if __name__ == "__main__":
    main()
```该解决方案是围绕直接数字操作构建的。 向后扫描检测单调性中断的位置。 一旦发现中断，递减前面的数字是确保最终数字严格小于或等于输入的最小变化，同时允许后缀变得最大。 

第二个向后循环是必要的，因为单个减量可能会在数字的前面创建一个新的违规。 如果没有这个传播步骤，像 332 这样的情况将错误地生成中间无效前缀。 

用 9 替换后缀可以保证最大值：一旦前缀固定，后面的数字就不能超过 9，任何较小的选择都会产生较小的有效数字，这是次优的。

 ## 边缘情况

 对于像 10 这样的输入，算法会在第二个数字处检测到单个违规。 它将第一个数字递减为 0 并将后缀设置为 9，在删除前导零后生成 9。 扫描和校正直接处理这个问题，无需任何特殊的外壳。 

对于像 11110 这样的输入，违规发生在最后一位数字。 该算法将前面的 1 减少为 0，然后在必要时进行传播，产生成为 1110 的前缀，然后填充后缀，最终产生 1119。单调检查确保传播后不会留下任何隐藏的违规行为。 

对于像 1234 这样已经很整齐的数字，在扫描中没有检测到违规，因此不会修改任何数字并立即返回原始数字，从而确认该算法不会过度纠正有效前缀。
