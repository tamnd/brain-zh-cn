 ## 解决方案
 ## 问题理解

 我们有一个 _n_×_n_ 网格，其中每个单元格包含一个整数，可以是正数或负数。 Furik 从左上角 (1,1) 开始，仅向右或向下移动，而 Rubik 从右下角 (n,n) 开始，仅向左或向上移动。 总分是他们访问的单元格中所有数字的总和，但每个单元格只计数一次，即使两个跑步者都通过它。 我们的目标是最大化他们可以收集到的总分。 

输入是网格的大小，后跟每个单元格中的值。 输出是一个整数，即可达到的最大分数。 

约束条件适中：_n_ 最多可达 300，单元格值范围从 -1000 到 1000。这允许我们使用 _n_ 为三次或更好的算法，但任何在 _n_ 为指数的方法都会失败。 对两个跑步者的所有可能路径进行简单的暴力破解显然是不可行的，因为路径的数量大约为 2^(2n)，对于 n=300 来说，这将变得天文数字般大。 

不明显的边缘情况包括非常小的网格，例如 n=1，其中 Furik 和 Rubik 从同一单元开始。 在这里，单元格只应计数一次，因此答案是单元格值本身。 另一个微妙的情况是当所有值都为负时； 跑步者可能仍然需要完全遍历网格，因此算法必须处理沿路径减少的总和。 如果只有一名跑步者可以通过高值单元格，则算法必须选择最佳分配以避免重复计算。 

## 方法

 暴力方法考虑了 Furik 的每条可能路径，然后考虑 Rubik 的每条可能路径，计算每对的总分。 虽然正确，但路径对的数量呈指数增长，大致为 (2^(2n))^2，即使对于像 20 这样的小 n，这也是不可能的。主要问题是跑步者的路径仅通过共享单元进行交互，并且跟踪所有路径组合是不可行的。 

关键的见解是将其建模为动态规划问题，其中可以沿着同一时间线同时跟踪两个跑步者的位置。 如果我们考虑跑步者按步移动——在每一步，Furik 和 Rubik 都采取了相同的步数——那么 Furik 的位置 (i1,j1) 和 Rubik 的位置 (i2,j2) 满足 i1+j1 = step+2 和 i2+j2 = 2n-step。 这使我们能够将问题简化为3维DP：dp[i1][i2][step]，表示Furik在i1行且Rubik在i2行之后的最大分数`step`移动。 相应的列可以推断为 j1 = step+2-i1, j2 = 2n-step-i2。 DP 转换处理 Furik 和 Rubik 的四种运动组合，同时避免重复计数单元。 

暴力破解之所以有效，是因为所有路径都有效，但当 n > 10 时，它会失败。观察到跑步者可以通过步数同步，将问题简化为多项式 DP，这对于 n=300 是可行的。

 | ---| ---| ---| ---|
 | 蛮力 | O(4^(2n)) | O(4^(2n)) | O（？）| 太慢了 |

 ## 算法演练

 1. 将DP表示为dp[i1][i2]，其中i1是Furik的行，i2是Rubik的行，当前步t = i1 + j1 - 2 = (2n - i2 - j2)。 相应的列是 j1 = t - i1 + 2 和 j2 = n - i2 + n - t。 
2. 初始化 dp[1][1] = grid[0][0]，因为两个跑步者都从各自的角开始。 如果它们从同一个单元格开始，则仅计数一次。 
3. 迭代从 1 到 2n-2 的所有可能步骤。 对于每个步骤，迭代所有可行的 i1 和 i2 值，以使 j1 和 j2 保持在网格边界内。 
4. 对于每个 (i1,i2) 对，计算上一步的最大 DP 值。 跑步者有四种可能的运动组合：都向下移动、都向右移动、一个向下/一个向右移动、以及相反。 取这些转变中的最大值。 
5. 将当前单元格的值添加到 DP 值中。 如果Furik和Rubik占据同一个单元格，则仅添加一次。 否则，对两个单元格求和。 
6. 继续这个过程，直到两个跑步者都到达目的地：Furik 位于 (n,n)，Rubik 位于 (1,1)。 dp[n][n] 处的值（针对索引进行调整）包含最大分数。 

工作原理：在每一步，DP 都会根据跑步者的位置和步数存储可达到的最大总和。 通过同步步骤，我们可以一次正确地计算重叠单元格。 DP 转换涵盖了所有移动可能性，因此不会遗漏任何潜在路径，从而确保最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
grid = [list(map(int, input().split())) for _ in range(n)]

dp = [[-float('inf')] * n for _ in range(n)]
dp[0][0] = grid[0][0]

for t in range(1, 2 * n - 1):
    new_dp = [[-float('inf')] * n for _ in range(n)]
    for i1 in range(max(0, t-(n-1)), min(n, t+1)):
        j1 = t - i1
        if j1 >= n: continue
        for i2 in range(max(0, t-(n-1)), min(n, t+1)):
            j2 = t - i2
            if j2 >= n: continue
            val = grid[i1][j1]
            if i1 != i2 or j1 != j2:
                val += grid[i2][j2]
            best = -float('inf')
            for pi1, pi2 in [(i1-1,i2-1),(i1-1,i2),(i1,i2-1),(i1,i2)]:
                if 0 <= pi1 < n and 0 <= pi2 < n:
                    best = max(best, dp[pi1][pi2])
            new_dp[i1][i2] = best + val
    dp = new_dp

print(dp[n-1][n-1])
```该代码首先读取网格并初始化一个具有负无穷大的 DP 表来表示无法到达的状态。 它迭代所有可能的步数，计算有效位置并考虑之前的四种组合。 使用`max`确保选择最佳的先前状态。 重叠单元格的值添加一次。 最终 DP 表的右下角包含两位参赛者的最高得分。
