 ## 解决方案
 ## 问题理解

 我们得到一个对象集合，每个对象提供一个有符号值和一个二进制掩码。 我们必须选择一个正整数`s`。 一次`s`是固定的，每个对象要么保持原样，要么根据下式计算的奇偶校验条件翻转符号`s`和它的面具。 

具体来说，对于我们计算的每个对象`t_i = s & mask_i`。 然后我们计算有多少个设置位`t_i`。 如果此计数为奇数，则该值`val_i`被否定，否则保持不变。 处理完所有对象后，我们将所有修改值相加。 目标是选择`s`这样最终的总和与原始总和具有相反的符号并且不为零。 

输入大小很大，最多 3 · 10^5 个对象，每个掩码最多可容纳 62 位。 这立即排除了任何尝试迭代所有可能的方法`s`， 自从`s`它本身生活在一个大小为 2^62 的空间中。 甚至尝试评估单个候选人`s`需要扫描所有对象，因此任何可行的解决方案都必须构建一个良好的`s`直接来自线性或接近线性时间的聚合结构。 

一个天真的观点是认为我们正在选择位的子集`s`，因为每个位都独立贡献`s & mask_i`。 然而，AND 结果中设置的位数的奇偶校验对于每一位来说不是线性的； 它取决于每个掩码内的位组合。 这就是大多数直接的贪婪想法失败的地方。 

当除一个大异常值外所有值均为正值或全部为负值时，就会出现微妙的边缘情况。 尝试独立翻转“贡献最大的掩码”的天真贪婪者可能会失败，因为翻转其中的一位`s`同时以不可预测的奇偶校验模式影响许多掩模。 

## 方法

 暴力方法将枚举所有可能的值`s`从 1 到 2^62 − 1，计算每个候选结果的变换总和，并检查符号。 这是正确的，因为它直接模拟了该过程，但它是不可行的：即使测试 10^6 个候选者也已经太慢了，而且整个空间是天文数字。 

关键的结构观察是，我们实际上并不关心确切的变换后的总和，只关心它是正数还是负数。 每个对象贡献要么`+val_i`或者`-val_i`，因此转换定义了数组上的符号翻转模式。 

奇偶校验条件可以重新解释：对于每个对象，符号翻转由以下位集之间的交集的奇偶校验确定：`s`和位集`mask_i`。 这正是 GF(2) 的二进制向量之间的点积的奇偶性`s`和`mask_i`。 

所以每个对象贡献一个因子`(-1)^{<s, mask_i>}`在哪里`< , >`是异或点积奇偶校验。 最终的和成为指数符号翻转内 GF(2) 线性形式的函数。 关键的简化是整个转换仅取决于由位引起的奇偶校验结构`s`。 

我们可以考虑选择`s`一点一点。 每个位独立地参与翻转掩码子集：位`k`影响所有设置了该位的掩码。 对于固定的`k`，切换它会翻转包含该位的所有掩码的奇偶校验。 这使我们能够逐步推断每一位对最终总和的影响。 

我们不是求解确切的最佳位子集，而是利用一个建设性的事实：总是存在一个位位置，仅激活该位位置就已经使变换后的总和过零或至少在与先前选择的位贪婪地组合时沿正确的方向改变符号。 这减少了根据边际效应贪婪地选择比特贡献子集的任务。 

我们维护当前的总和并评估切换每一位的效果。 对于每一位`k`，我们计算如果包含它的话有多少个值会翻转符号。 这可以通过针对每个位预先计算其掩码包含当前奇偶校验状态中的该位的对象之间的贡献差来完成。 

贪婪的建造`s`从最高位到最低位，确保每次包含都使总和更接近符号反转。 由于每个位以受控方式影响不相交奇偶校验贡献，因此该过程稳定在 O(62·n) 内。

 ## 算法演练

 我们将问题重新表述为选择`s`一位一位，同时跟踪每一位如何影响符号翻转模式。 

1. 计算初始总和`S = sum(val_i)`。 如果`S > 0`，我们希望最终的总和变为负数； 否则我们希望它是积极的。 
2. 预先计算每个位的位置`k`（0 到 61）对象的集合，其`mask_i`有位`k`放。 这让我们可以快速评估激活位的效果`k`。 
3. 维护每个对象的当前“符号状态”，最初全部为正（在`s`但意味着没有翻转）。 
4. 对于从高到低的每一位，模拟如果我们切换该位会发生什么`s`。 这需要重新计算奇偶校验效应：对于掩码包含该位的所有对象，它们的符号将相对于当前状态翻转。 
5. 如果包含该位，则计算所得的新总和。 由于翻转交换符号，该变化的计算方法是减去当前正数计数的所有受影响对象的贡献值减去负数的两倍。 
6. 如果该位使总和更接近目标符号或需要过零，则选择该位。 相应地更新当前标志状态。 
7. 继续，直到处理完所有位。 输出构建的`s`。 

### 为什么它有效

 中的每一位`s`定义对象集上的独立异或奇偶校验切换。 虽然这些切换在最终总和中相互作用，但贪婪的构造仍然有效，因为每一步都会评估局部决策的确切全局效果。 由于每个位翻转都是根据完整的当前状态进行评估的，因此后面的位不会使早期的最优性决策无效。 该过程保持当前总和的一致变换，并且在终止时，累积变换必须落在两个符号区域之一，并由问题陈述保证存在。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    vals = []
    masks = []
    
    total = 0
    for _ in range(n):
        v, m = map(int, input().split())
        vals.append(v)
        masks.append(m)
        total += v

    # We will maintain current contribution after applying chosen bits
    cur = vals[:]

    s = 0

    for b in reversed(range(62)):
        # try flipping bit b in s
        flipped = cur[:]
        
        for i in range(n):
            if (masks[i] >> b) & 1:
                flipped[i] = -flipped[i]

        new_sum = sum(flipped)

        # target is to move toward opposite sign of original total
        if total > 0:
            # want negative
            if new_sum < total and new_sum != 0:
                s |= (1 << b)
                cur = flipped
        else:
            # want positive
            if new_sum > total and new_sum != 0:
                s |= (1 << b)
                cur = flipped

    print(s)

if __name__ == "__main__":
    solve()
```此实现显式模拟每个位对整个数组状态的影响。 尽管它会重新计算每位的总和，但固定的 62 位限制使解决方案在典型约束下的 Python 中保持在可接受的范围内。 

每个位都根据当前转换状态进行隔离测试。 如果应用它改善了符号反转的方向，则它被提交。 关键细节是我们始终根据当前的转换值而不是原始值进行评估，以确保累积效果的一致性。

 ## 边缘情况

 一个关键的边缘情况是所有掩码都相同。 在那种情况下，每一点`s`同时翻转所有元素，这意味着整个转换简化为保持总和或取反。 该算法自然地处理这个问题，因为每个位评估在所有对象上都会看到相同的效果，并且当且仅当它翻转全局符号时它才会选择一个位。 

另一种边缘情况是只有一个对象具有非零值。 然后，如果选择了其掩码中存在的任何位，则立即翻转符号，并且贪婪选择将接受产生反转的任何有效位。 逐步评估保证了在需要时会选择这样的位。 

第三种情况是初始总和的绝对值已经接近于零。 即便如此，该算法也不依赖于幅度启发法； 它总是评估精确的结果总和，因此它通过拒绝产生零的转换来正确地避免意外的零输出。
