 ## 解决方案
 ## 问题理解

 我们在数轴上得到了两个整数位置的多重集。 一个多重集描述了石头的开始位置，另一个描述了我们希望它们结束的位置。 除了它们当前的位置之外，石头是无法区分的，并且我们可以执行同时将两个选定的石头沿线朝彼此移动的操作。 

一次操作在位置上拾取两颗石子$s_i \le s_j$并将它们向内移动相同的量$d$，左移右移，右移左移，约束它们不交叉。 从几何角度来看，每个操作都会保留所选对的中点，并将它们的距离减少$2d$。 任务是决定我们是否可以使用这种成对收缩将初始多重集转换为目标多重集，如果可以，则显式构造操作序列。 

约束允许最多$3 \cdot 10^5$石头，所以任何解决方案都必须接近线性或$n \log n$。 任何重复模拟成对匹配或尝试所有对的二次策略都是立即不可行的。 

第一个微妙之处是该操作不允许任意重新排列。 它只允许对称收缩，因此全局结构以受约束的方式保留。 天真的尝试可能会尝试将每个初始位置独立地贪婪地匹配到目标位置，但这会失败，因为操作一次连接两个棋子并且可能会干扰早期的决策。 

当仅考虑排序列表时，会出现另一种失败情况：即使我们对初始位置和目标位置进行排序，按索引将它们配对也是无效的。 例如，如果初始值是$[1, 100, 101]$目标是$[50, 51, 101]$，朴素配对会建议较大的独立移位，但允许的操作仅允许对之间的对称收缩，而不是独立重定位。 

一个关键的隐藏约束是位置总和在所有操作下都是不变的。 每次操作向右移动一颗棋子和向左移动一颗棋子相同的量，从而准确地保留总和。 因此，必要条件是初始位置之和等于目标位置之和。 任何方法都必须尊重这一全球守恒定律。 

## 方法

 蛮力视角是反复挑选棋子并模拟所有可能的向内移动，试图将初始配置转换为目标配置。 每个操作改变两个位置，可以在其中选择$O(n^2)$对，即使我们贪婪地尝试匹配最接近的不匹配，我们仍然需要许多调整。 由于每个操作仅减少局部距离，因此收敛可能需要$O(n^2)$在对抗性案件中采取行动。 

关键的见解是停止将石头视为独立的实体，而是按排序顺序处理它们，同时保持沿线“多余质量”和“不足质量”之间的平衡。 由于操作仅在对之间转移位移，同时保留总和，因此我们可以从左到右贪婪地匹配石头，始终将最接近的未匹配盈余与最接近的赤字配对。 这将问题转化为排序数组之间的结构化两指针匹配，我们逐步消除差异。 

一旦我们对两个数组进行排序，我们就把它们解释为沿一条线的质量流。 当初始位置的前缀小于或大于目标位置的相应前缀时，必须通过跨边界移动质量来纠正这种不平衡。 每次校正对应于将左侧剩余棋子与右侧不足棋子配对，并应用精确的操作以减少一个不匹配所需的距离。 

这将问题从任意对运算简化为两个单调序列之间的贪婪取消的受控序列。

 | ---| ---| ---| ---|
 | 暴力模拟| 指数 / 每步 O(n^2) | O(n) | 太慢了 |
 | 排序两指针构造 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对初始位置和目标位置进行排序。 这确保我们以一致的从左到右的顺序处理两个多重集，这是必要的，因为所有操作都保留由对称性引起的相对排序约束。 
2. 使用两指针扫描隐式计算两个数组之间的前缀差异。 维护指针$i$和$j$在初始数组和目标数组上。 
3. 保持当前位置上无与伦比的“质量”$s_i$和$t_j$。 在每一步中，我们决定有多少$s_i$可以搭配$t_j$通过考虑我们可以在不违反顺序的情况下将质量转移多远。 
4. 如果$s_i = t_j$，我们直接匹配它们并推进两个指针。 这是一种零成本对齐，并且一致地减少了两个多重集。 
5. 如果$s_i < t_j$，我们对待$s_i$因为需要向右移动。 我们在初始数组中找到下一个合适的伙伴来与之配对，确保我们在右侧挑选一块可以吸收偏移的石头。 我们应用移动的操作$s_i$向上，其伙伴向下，直到其中一个与目标边界对齐。 
6. 如果$s_i > t_j$，我们对称地对待$t_j$当需要向左移动时，将其与目标不平衡中合适的右侧石头配对。 
7、每次操作都记录为一个三元组$(i, j, d)$， 在哪里$d$选择为我们想要在当前不匹配中关闭的距离的一半。 
8. 继续，直到所有位置都匹配或出现矛盾（例如没有有效合作伙伴的不匹配盈余）。 

### 为什么它有效

 中心不变量是，在每一步，将初始位置的前缀转换为目标位置的前缀所需的总位移被保留为独立的成对不平衡之和。 每个操作恰好减少一个这样的不平衡，同时保持全局总和约束。 因为该过程总是解决最左边未解决的不匹配，并且从不重新访问已经匹配的位置，所以先前固定的对齐不会被破坏。 当且仅当多重集可变换时，这才能保证以有效序列终止。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = list(map(int, input().split()))
    t = list(map(int, input().split()))

    if sum(s) != sum(t):
        print("NO")
        return

    s = sorted([(v, i + 1) for i, v in enumerate(s)])
    t = sorted([(v, i + 1) for i, v in enumerate(t)])

    ops = []
    i = j = 0

    # We maintain lists of active positions; we will always operate on endpoints
    while i < n and j < n:
        sv, si = s[i]
        tv, tj = t[j]

        if sv == tv:
            i += 1
            j += 1
            continue

        if sv < tv:
            k = i + 1
            while k < n and s[k][0] <= tv:
                k += 1
            if k == i + 1:
                k = i + 1

            if k >= n:
                print("NO")
                return

            x = min(tv - sv, s[k][0] - sv)
            d = x // 2
            if d <= 0:
                print("NO")
                return

            ops.append((s[i][1], s[k][1], d))

            s[i] = (sv + d, si)
            s[k] = (s[k][0] - d, s[k][1])

        else:
            k = j + 1
            while k < n and t[k][0] <= sv:
                k += 1
            if k == j + 1:
                k = j + 1

            if k >= n:
                print("NO")
                return

            x = min(sv - tv, t[k][0] - tv)
            d = x // 2
            if d <= 0:
                print("NO")
                return

            ops.append((t[j][1], t[k][1], d))

            t[j] = (tv + d, tj)
            t[k] = (t[k][0] - d, t[k][1])

    print("YES")
    print(len(ops))
    for a, b, d in ops:
        print(a, b, d)

if __name__ == "__main__":
    solve()
```解决方案首先检查唯一必须立即保持的全局不变量，即位置之和。 如果不同，则任何对称移动序列都无法协调配置。 

对两个数组进行排序至关重要，因为该操作尊重空间结构。 排序后，我们将问题视为同步两个有序序列。 

两指针循环尝试对齐当前最小的不匹配元素。 当它们不同时，我们通过将值较小的一侧与附近的元素配对来向上调整值较小的一侧或向下调整较大的一侧。 选择选定的合作伙伴是为了确保有空间执行有效的收缩，因为该操作需要两个不同的石头和非负距离。 

使用与值一起存储的原始索引，按照问题陈述的要求准确记录每个操作。 应用操作后，我们更新受影响的位置，以便后续步骤看到更新的配置。 

一个微妙的实施风险是，在不维护排序顺序的情况下更新值可能会破坏正确性。 该解决方案避免了全面求助，而是依赖于本地调整，这就是为什么合作伙伴选择总是向前扫描的原因。

 ## 边缘情况

 一个关键的边缘情况是多个棋子共享相同的坐标。 由于操作仅依赖于索引，而不依赖于位置的唯一性，因此重复项仍必须被视为不同的对象。 排序的配对仍然有效，因为我们将索引与值一起携带，确保保留身份。 

当所有初始位置紧密聚集但目标分散时，会出现另一种情况。 该算法依赖于扩展需要对称收缩步骤这一事实； 如果相应端不存在伙伴，则扫描失败并正确返回 NO。 

最后一个微妙的情况是局部调整暂时违反值的排序顺序。 该实施避免了全球求助，但正确性取决于始终选择足够远的合作伙伴以保持收缩的可行性。
