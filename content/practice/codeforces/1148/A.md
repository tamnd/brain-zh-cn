 ## 解决方案
 ## 问题理解

 我们得到了三个构建块池。 有`a`字母串的片段`"a"`,`b`的碎片`"b"`， 和`c`的碎片`"ab"`。 我们可以选择这些块的任何子集并以我们想要的任何顺序连接它们。 

生成的连接字符串必须是“好”的，这意味着它严格交替字符：两个相邻字符不能相同。 所以有效的字符串看起来像`ababab...`或者`babab...`，但从不包含`aa`或者`bb`任何地方。 

每个`"a"`块贡献一个`a`， 每个`"b"`贡献一个`b`，以及每个`"ab"`贡献两个角色`a`然后`b`。 任务是最大化最终好的字符串的总长度。 

约束条件达到`10^9`，这立即排除了任何模拟构造或尝试块排列的方法。 任何解决方案都必须将问题简化为恒定数量的算术推理。 该结构完全是贪婪和奇偶驱动的。 

一个微妙的点是`"ab"`块是有方向的。 他们总是做出贡献`a`然后`b`，因此它们不能自由翻转。 这与交替约束相互作用，并使它们的行为有所不同，具体取决于我们是否以最终字符串开头`a`或者`b`。 

一个天真的错误是假设所有块只是独立贡献长度，给出`a + b + 2c`。 这会失败，因为串联可能会强制块边界处的相邻字符相等。 

例如，如果`a = 1, b = 1, c = 1`，朴素长度是`4`，这可以实现为`baba`。 但如果`a = 2, b = 2, c = 0`，天真的推理可能仍然有效，但如果在更一般的情况下忽略奇偶校验，排序可能会失败`"ab"`阻止力的转换。 

真正的困难在于决定有多少`"ab"`我们可以安全地使用块，同时保持交替，因为它们有效地偏置了序列结构。 

## 方法

 暴力破解的想法是将每个块视为一个项目，并尝试所有子集和所有排列，构建字符串并检查有效性。 这是正确的，但完全不可行。 子集的数量是`2^(a+b+c)`在最糟糕的概念形式中，即使我们只排列类型，排序复杂性也会爆炸。 即使抽象很小，状态空间也是指数级的。 

关键的观察是最终的字符串完全由其起始字符和总计数决定`a`和`b`用过的。 一个好的字符串严格交替，因此一旦选择了第一个字符，整个模式就固定了：`a b a b ...`或者`b a b a ...`。 

这将问题减少到选择多少`"ab"`我们可以在不破坏交替一致性的情况下包含块。 每个`"ab"`贡献一`a`和一个`b`以固定的顺序，因此它总是在本地保留交替。 唯一的全球性问题是混合`"ab"`具有独立功能的块`"a"`和`"b"`块可能会造成可用之间的不平衡`a`和`b`位置取决于交替链的奇偶性。 

我们可以考虑构建一个带有计数的长交替序列：`A_total = a + c`,`B_total = b + c`。 

但我们并不总是能够完全实现这两个方向，因为`"ab"`块力结构。 最终的答案仅取决于我们是否可以开始`a`或者`b`以及在强加的配对结构之后还剩下多少额外的不匹配的字母`"ab"`块。 

最佳策略简化为检查可能的起始字符并贪婪地使用所有字符`"ab"`块，因为它们永远不会损害内部的交替。 唯一的限制是我们是否有足够的独立字母来维持吸收后的交替`c`配对单位。 

这会分解为一小组基于奇偶校验的算术案例`a + c`和`b + c`。

 ## 算法演练

 1. 观察每个`"ab"`块贡献一个强制转换`a -> b`，所以我们总是包括所有`c`块处于最佳构造中，因为它们永远不会在内部创建无效的邻接关系。 这既增加了`a`和`b`可用性对称。 
2. 定义有效计数`A = a + c`和`B = b + c`，表示考虑后每个角色的总可用性`"ab"`块。 
3. 一个有效的交替字符串开头`a`使用模式`a b a b ...`。 该约束下的最大长度为`2 * min(A, B) + (A > B ? 1 : 0)`。 

原因是我们交替进行直到一种字符类型用完，并且如果`a`比较频繁，我们可以多放一个`a`在最后。 
4. 类似地计算最佳长度，如果从`b`，交换角色`A`和`B`。 
5. 取两个起始选择中的最大值。 

### 为什么它有效

 任何好的字符串完全由其起始字符和交替约束决定。 一旦启动固定，顺序就被强制，只能消耗`a`和`b`以交替顺序。 的存在`"ab"`除了为每个字符贡献一个单位之外，块不会引入灵活性，因此它们可以被视为两个计数的中性增量。 因此，最佳答案是两个确定性交替结构中最好的一个。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def best(a, b):
    # start with 'a'
    if a >= b:
        return 2 * b + 1
    return 2 * a

a, b, c = map(int, input().split())

A = a + c
B = b + c

ans = max(best(A, B), best(B, A))
print(ans)
```该实现将整个问题简化为计算两个候选交替序列。 帮手`best`当我们通过排序隐式固定起始字符时，计算最长的交替字符串`A`和`B`。 

关键的微妙之处在于折叠`"ab"`同等地分块到两个计数中，这保留了对称性并允许对起始奇偶校验情况进行独立评估。

 ## 边缘情况

 当`c = 0`，问题简化为仅从单字母块形成最长的交替字符串。 该公式仍然有效，因为`A = a`,`B = b`，并且结构退化为纯粹的交替，没有任何结构扭曲`"ab"`块。 

例如，输入`a = 3, b = 1, c = 0`给出`A = 3, B = 1`。 开始于`a`产量`2 * 1 + 1 = 3`，匹配最佳可能的字符串`abab?`正确截断为`aba`。 开始于`b`产生较小的值，因此最大值是正确的。 

什么时候`a = b = 0`，所有的贡献都来自于`"ab"`块。 结果变成`2c`，因为每个块都贡献`ab`它们干净地连接成一个交替的链。 公式给出`A = B = c`，生产`2c`。 

例如`0 0 3`给出`A = B = 3`， 导致`6`，对应于`ababab`，确认堆叠`"ab"`块永远不会违反交替。
