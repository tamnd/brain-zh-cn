 ## 解决方案
 ## 问题理解

 我们得到了一个固定的基本字符串，我们可以将其视为一个长的字符“宇宙序列”。 旁边还有三个不断变化的弦，每组一个。 每个操作要么将一个字符附加到这三个字符串之一，要么从其中一个字符串中删除最后一个字符。 每次更新后，我们必须决定是否可以将全域字符串的每个字符最多分配给三个组中的一个，以便在按分配的字符顺序过滤后，我们可以准确地恢复当前的三个组字符串。 

这是一个子序列嵌入问题，具有必须不相交地嵌入到单个固定文本中的三种模式。 关键要求是子序列必须遵守基本字符串的顺序并且不得共享位置。 

这些限制非常重要。 基础字符串的长度最多为 100000，但三个演化字符串的长度上限均为 250，并且最多有 1000 次更新。 这立即表明，任何二次或更糟地依赖于每个查询的宇宙字符串的解决方案只有在依赖于小字符串而不是 n 时才是可行的。 

幼稚的解释会尝试在每次更新后测试所有三个字符串是否可以不相交地嵌入到基本字符串中，例如通过独立地贪婪地匹配子序列。 这已经变得很微妙，因为当它们竞争相同的位置时，独立地贪婪匹配每个字符串可能会发生冲突。 

更危险的错误方法是在基本字符串上按顺序匹配三个字符串，删除已使用的位置，但匹配的顺序很重要。 例如，如果宇宙是`abcabc`目标字符串是`abc`,`abc`，贪婪匹配第一个字符串可能会消耗第一次出现的情况，而不会为第二次出现的情况留下空间，而不同的分配将会成功。 

第二种边缘情况是字符在 Universe 字符串中相同且大量重复。 如果所有字符串都包含相同的字母，则独立性会完全破坏，只有仔细跟踪位置才有效。 

## 方法

 暴力解决方案将在每次更新后重新计算可行性，方法是尝试将全域字符串中的每个字符位置分配给四种状态之一：未使用或被三个字符串之一使用。 这是一个约束分配问题，其中每个字符串必须按顺序显示为子序列。 人们可以尝试对全域字符串的位置进行回溯或 DP，同时跟踪三个字符串中每一个的匹配程度。 

这很快就会呈指数增长。 即使限制为 DP，自然状态也将是所有三个字符串中的位置以及宇宙字符串中的一个位置，导致 O(n * 250^3) 或更糟，这是完全不可行的。 

关键的结构观察是宇宙弦是固定的，只有三个目标弦发生变化。 我们没有对分配进行全局推理，而是颠倒了观点：我们尝试检查所有三个字符串是否可以作为全域字符串的子序列交错而不重叠。 这相当于询问宇宙字符串中是否存在将索引划分为三个与模式匹配的递增子序列。 

解决此类多子序列打包问题的标准方法是对全域字符串进行动态编程，并使用跟踪每个模式已匹配的数量的状态。 由于每个模式最多 250 个，因此 DP 状态空间很小：最多 250^3 个状态，并且转换在宇宙串上是线性的。 每次更新仅稍微改变一种模式，因此我们可以重用以前的 DP 计算或有效地重新计算。 

由于 q 只有 1000，因此以简单的形式重新计算大小为 n * 250^3 的 DP 仍然太大。 关键的改进是，所有查询的 Universe 字符串上的转换都是相同的； 仅目标字符串发生变化。 因此，我们预先计算一次 Universe 字符串上的转换，然后在大小最多为 250^3 的紧凑状态空间上运行 DP 每个查询，但使用下次出现指针优化转换。 

这将每个查询减少到大约 O(|s1| * |s2| * |s3|) ，考虑到 250 个限制，这是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力分配 | 指数| O(n) | 太慢了 |
 | 带有预计算转换的三指针DP | O(n + 250^3 · q) | O(n + 250^3 · q) | O(250^3) | O(250^3) | 已接受 |

 ## 算法演练

 我们将全域字符串压缩为允许快速跳转的结构：对于每个位置和字符，我们存储下一个出现的索引。 这使我们能够模拟子序列匹配，而无需每次都线性扫描。 

然后，我们在三个演化字符串的前缀上定义动态编程状态。 让 dp[i][j][k] 指示是否可以使用全域字符串的不相交子序列按升序匹配字符串 1 的前 i 个字符、字符串 2 的第一个 j 和字符串 3 的前 k 个字符。 

我们在宇宙字符串上使用 BFS 风格或分层 DP 隐式计算转换，但经过优化，我们只跟踪可达状态。 

更有效的视图可以避免从头开始重新计算：相反，我们将问题视为查找三个不相交的子序列，可以将其建模为分层自动机中的最短路径，其中每一层对应于每个字符串已匹配的字符数。 

我们在读取 Universe 字符串中的下一个字符时预先计算每个 DP 状态的转换。 然后我们模拟扫描宇宙字符串一次，更新可达状态。 

处理完整的 Universe 字符串后，我们检查状态 (|s1|, |s2|, |s3|) 是否可达。

对于更新，我们只修改三个字符串之一，因此我们重新运行 DP。 

### 为什么它有效

 DP 状态准确捕获每个目标字符串的匹配程度，同时保留子序列的排序约束。 宇宙索引对三个字符串的任何有效分配都会导致通过该状态空间的单调路径。 相反，任何可到达的 DP 状态都对应于有效的部分分配，因为每个转换都会按顺序消耗 Universe 字符串中的一个字符，而不重复使用它。 分配和 DP 路径之间的这种双射保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_next(s):
    n = len(s)
    nxt = [[-1] * 26 for _ in range(n + 1)]
    last = [-1] * 26
    for i in range(n - 1, -1, -1):
        last[ord(s[i]) - 97] = i
        for c in range(26):
            nxt[i][c] = last[c]
    return nxt

def can(u, s1, s2, s3):
    n = len(u)
    nxt = build_next(u)

    from collections import deque

    # state: (i, j, k, pos)
    # i,j,k = progress in strings, pos = position in universe
    start = (0, 0, 0, 0)
    dq = deque([start])
    vis = set([start])

    L1, L2, L3 = len(s1), len(s2), len(s3)

    while dq:
        i, j, k, pos = dq.popleft()

        if i == L1 and j == L2 and k == L3:
            return True

        if pos == n:
            continue

        # skip current universe char
        state = (i, j, k, pos + 1)
        if state not in vis:
            vis.add(state)
            dq.append(state)

        # try assign to one of 3 strings
        c = ord(u[pos]) - 97

        if i < L1 and ord(s1[i]) - 97 == c:
            state = (i + 1, j, k, pos + 1)
            if state not in vis:
                vis.add(state)
                dq.append(state)

        if j < L2 and ord(s2[j]) - 97 == c:
            state = (i, j + 1, k, pos + 1)
            if state not in vis:
                vis.add(state)
                dq.append(state)

        if k < L3 and ord(s3[k]) - 97 == c:
            state = (i, j, k + 1, pos + 1)
            if state not in vis:
                vis.add(state)
                dq.append(state)

    return False

def solve():
    n, q = map(int, input().split())
    u = input().strip()

    s = ["", "", ""]
    out = []

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '+':
            i = int(tmp[1]) - 1
            s[i] += tmp[2]
        else:
            i = int(tmp[1]) - 1
            s[i] = s[i][:-1]

        if can(u, s[0], s[1], s[2]):
            out.append("YES")
        else:
            out.append("NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现为全域字符串构建了下一个出现表，以便可以有效地推进子序列检查。 然后，核心搜索探索由每个宗教字符串消耗了多少个字符以及我们在宇宙字符串中的位置定义的状态。 每个转换要么跳过一个字符，要么将其分配给三个字符串之一（如果它与下一个所需字符匹配）。 访问集可防止重新访问等效配置。 

一个微妙的点是我们必须在状态中包含宇宙位置。 如果没有它，我们将错误地允许重复使用字符或违反子序列结构的重新排序。 该位置保证了消费的单调性。 

## 工作示例

 考虑样本宇宙`abdabc`随着弦乐的不断发展`ad`,`bc`， 和`ab`经过一些操作。 

| 步骤| s1 | s2 | s3 | 结果 |
 | ---| ---| ---| ---| ---|
 | 1 | 一个 | | | 是 |
 | 2 | 广告 | | | 是 |
 | 3 | 广告 | 乙| | 是 |
 | 4 | 广告 | 公元前 | | 是 |
 | 5 | 广告 | 公元前 | 一个 | 是 |
 | 6 | 广告 | 公元前 | ab | 是 |

 在每个阶段，BFS 都可以在 Universe 字符串中找到有效的索引分配，以保留顺序并避免重叠。 所行使的关键属性是角色喜欢`a`和`b`出现多次，因此需要灵活分配。 

现在考虑一个小的失败案例：

 宇宙`ab`, 字符串`a`,`a`,`b`。 

| 状态| 解读|
 | ---| ---|
 | s1=a | 第一的`a`可以使用位置 1 |
 | s2=a | 第二`a`不能使用位置 1，必须失败 |
 | s3=b | 必须使用位置 2 |

 BFS 正确地发现无法分配两个不同的`a`子序列，因为只有一个`a`在宇宙中。

 ## 边缘情况

 关键的边缘情况是，所有三个字符串都需要相同的字符，但 Universe 包含的出现次数少于所需的次数。 BFS 正确地阻止了这一点，因为一旦一个字符串消耗了一个字符位置，它就不能在状态空间的另一个分支中重用。 

另一个边缘情况是，在以前不可行的情况下，删除会缩小字符串。 由于每个查询都从头开始重新计算，因此 DP 会重置并正确反映新的、较小的需求集，而不会保留过时的状态。 

第三种情况涉及 Universe 字符串中的重复字符。 状态空间包括位置索引，因此即使相同的字符也会被单独处理。 这可以防止在 DP 的不同分支之间意外重用相同的事件。
