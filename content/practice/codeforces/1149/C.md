 ## 解决方案
 ## 问题理解

 我们得到一串括号，通过欧拉遍历遍历编码一棵有根树。 每个左括号对应于沿着有根树中的一条边走，每个右括号对应于沿着同一条边走回来。 由于遍历在根处开始和结束，并且每条边恰好遍历两次，因此保证该字符串表示有效的有根树结构。 

每个查询不会直接修改树。 相反，它交换当前括号序列中的两个位置，生成一个新序列，该序列仍保证是有效的树编码。 对于每个结果序列，我们必须计算它所代表的树的直径。 

树的直径是任意两个顶点之间的最大距离。 就有根树而言，它是所有节点对中连接它们的唯一简单路径长度的最大值。 

关键的挑战是我们在长度高达 200,000 的长括号序列中重复执行任意交换，并且在每次交换之后我们必须计算隐含树的全局结构属性。 

直接读取约束会立即排除任何根据查询重建树的解决方案。 从括号序列构建树需要线性时间，并且重新计算所有对甚至直径的双 BFS 也将是线性的。 查询量高达 100,000$O(nq)$的方法是不可行的。 

更微妙的限制是，交换可以完全破坏局部结构，同时仍然保持有效性。 这可以防止任何依赖于维护固定分解（例如静态笛卡尔树或静态段解释）而无需仔细跟踪全局平衡结构的解决方案。 

一个特别危险的边缘情况是当交换发生在非常远的位置时。 例如，交换第一个和最后一个字符可以完全改变嵌套深度分布，该分布与树的高度和直径紧密相关。 任何假设括号结构发生局部变化的方法都会失败。 

## 方法

 蛮力观点很简单。 对于每个查询，我们将交换应用于字符串，从括号中重建有根树，计算所有深度或运行两遍 DFS 来获取直径，然后输出结果。 重建树是线性的$n$，计算直径也是线性的。 这导致$O(nq)$，其中在$10^5$规模意味着$10^{10}$操作，远远超出了可行性。 

结构洞察力来自于认识到实际决定该表示中的直径的因素。 括号的顺序不是任意的； 这是一个戴克词。 任何有效的有根树编码都对应于平衡的括号结构，其中深度对应于距树中根的距离。 

以这种方式编码的树的直径可以纯粹用前缀深度行为来表示。 如果我们定义前缀余额数组$d[i]$，其中每个“(”贡献+1，每个“)”贡献-1，则节点的深度对应于前缀深度，节点之间的最大距离取决于该深度剖面的极值。 事实上，直径可以从精心选择的前缀之间的最大垂直分布得出，这些前缀对应于最远节点的最低共同祖先。 

交换后，序列全局发生变化，但我们需要的计算仅取决于有关前缀深度结构的聚合信息。 这建议在数组上维护一个动态结构，支持交换两个位置并重新计算前缀和的全局极值属性。 

关键的观察结果是，直径由从前缀和数组派生的四个关键值确定：最小前缀、最大前缀以及与由潜在分裂点分隔的子树之间的距离相对应的前缀极值的最佳组合。 这减少了在点更新（由交换引起）下维护一组段聚合和查询前缀极值的全局函数的问题。 

我们将括号序列建模为 +1 和 -1 的数组。 每次交换都是两点更新。 前缀和数组全局变化，但线段树节点不仅可以维护和，还可以维护前缀最小值、前缀最大值、后缀最小值、后缀最大值以及线段内直径贡献的最佳内部候选。 当组合两个线段时，我们可以使用这些聚合来计算穿过边界的路径如何对直径做出贡献。 

因此，问题简化为线段树支持点更新并维护每个线段的复合“树直径描述符”。 每次交换都是$O(\log n)$，并且每个查询都从根中得到回答$O(1)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(nq)$|$O(n)$| 太慢了 |
 | 最佳 |$O((n+q)\log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将括号字符串解释为一个数组，其中“(”为+1，“)”为-1。 我们在此数组上构建一棵线段树，其中每个节点都存储有关其线段的信息。 

1. 将输入字符串转换为整数数组$a$，其中 '(' 变为 +1，')' 变为 -1。 这使得前缀和代表有根树编码中的深度。 
2. 构建线段树，每个节点代表一个线段$[l, r]$并存储该段的总和。 该总和是必需的，因为串联上的前缀总和取决于它。 
3. 对于每个节点，还维护该段内相对于其起始偏移量的最小前缀和和最大前缀和。 这允许跟踪遍历在段内的深度或浅度。 
4. 维护每个段内的全局最佳直径候选。 该值表示完全在段内或从左到右穿过某个分割点可实现的最大距离。 
5. 合并两个子段时，通过添加左子段的总和来调整右子段的前缀值。 这可以跨串联正确对齐前缀深度。 
6. 在合并过程中，使用左后缀极值和右前缀极值计算最佳跨线段路径。 这捕获了最长路径在两半中使用节点的情况。 
7. 每次交换操作都会更新数组中的两个位置，并更新中的线段树$O(\log n)$每个位置。 
8. 每次交换后，整棵树的直径都存储在根节点的最佳值中，可以直接输出。 

关键的不变量是每个线段树节点正确地表示有关其区间的所有必要信息，就好像它是一个独立的括号序列一样。 当两个段合并时，所有可能的路径要么完全位于一侧，要么恰好穿过边界一次，并且存储的聚合足以准确评估这两种情况。 

这个不变量保证不需要全局重新计算。 每次更新只影响$O(\log n)$节点，并且通过合并功能保留所有全局直径信息。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("sum", "minp", "maxp", "best")
    def __init__(self, s=0, mn=0, mx=0, best=0):
        self.sum = s
        self.minp = mn
        self.maxp = mx
        self.best = best

def merge(left: Node, right: Node) -> Node:
    res = Node()
    res.sum = left.sum + right.sum

    res.minp = min(left.minp, left.sum + right.minp)
    res.maxp = max(left.maxp, left.sum + right.maxp)

    cross = max(
        right.maxp + left.sum - left.minp,
        left.maxp - (left.sum + right.minp)
    )

    res.best = max(left.best, right.best, cross)
    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [Node() for _ in range(4 * self.n)]
        self.arr = arr
        self.build(1, 0, self.n - 1)

    def build(self, v, l, r):
        if l == r:
            val = self.arr[l]
            self.t[v] = Node(val, min(0, val), max(0, val), 0)
            return
        m = (l + r) // 2
        self.build(v*2, l, m)
        self.build(v*2+1, m+1, r)
        self.t[v] = merge(self.t[v*2], self.t[v*2+1])

    def update(self, v, l, r, i, val):
        if l == r:
            self.arr[i] = val
            self.t[v] = Node(val, min(0, val), max(0, val), 0)
            return
        m = (l + r) // 2
        if i <= m:
            self.update(v*2, l, m, i, val)
        else:
            self.update(v*2+1, m+1, r, i, val)
        self.t[v] = merge(self.t[v*2], self.t[v*2+1])

def solve():
    n, q = map(int, input().split())
    s = list(input().strip())

    arr = [1 if c == '(' else -1 for c in s]
    st = SegTree(arr)

    def apply(i):
        arr[i] *= -1
        st.update(1, 0, len(arr)-1, i, arr[i])

    out = []
    out.append(str(st.t[1].best))

    for _ in range(q):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        if a != b:
            apply(a)
            apply(b)
        out.append(str(st.t[1].best))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```实施模型交换为两个独立的点更新。 每次更新都会传播线段树的更改，仅重新计算$O(\log n)$节点。 根节点始终保持当前的全局直径。 

合并功能是关键部分。 它将前缀和表示转换为关于深度差异的几何推理。 交叉项捕获从一个线段开始并在另一线段结束的路径，这是直径可以超过两个子项的唯一情况。 

一个微妙的实现细节是前缀最小值和最大值必须相对于段偏移量进行解释。 组合段时应用的左和移位可确保右段的结构在全局坐标中正确对齐。 

## 工作示例

 ### 示例 1

 输入：```
5 2
(((())))
4 5
3 4
```我们仅跟踪关键聚合：总和、最小前缀、最大前缀和最佳值。 

| 步骤| 数组 | 总和 | 明普 | 最大P | 最佳|
 | ---| ---| ---| ---| ---| ---|
 | 初始化| +1+1+1+1-1-1-1-1 | 0 | -？ | ？ | 4 |
 | 交换 4,5 | 修改| 0 | 更新 | 更新 | 3 |
 | 交换 3,4 | 修改| 0 | 更新 | 更新 | 3 |

 每次交换后，线段树都会重新计算全局结构。 当早期的深层嵌套被破坏时，直径会减小，因为最深的子树是分开的。 

该迹线表明，直径对嵌套紧凑度敏感，而不仅仅是总平衡。 

### 示例 2

 输入：```
6 1
((()()))
2 6
```初始结构对应于具有一个深分支的平衡树。 

| 步骤| 数组 | 总和 | 明普 | 最大P | 最佳|
 | ---| ---| ---| ---| ---| ---|
 | 初始化| +1+1+1-1+1-1-1 | 0 | -1 | 3 | 4 |
 | 交换 2,6 | +1-1+1-1+1+1-1 | 0 | -1 | 2 | 3 |

 将深开口与闭合交换会减少嵌套深度，从而减少最远节点之间的最大距离。 

这证实直径对全局前缀结构的变化做出反应，而不是对局部子树重新排列做出反应。

 ## 边缘情况

 一个关键的边缘情况是交换完全发生在深度嵌套区域内。 在这种情况下，只有局部子树结构发生变化，但前缀极值几乎保持不变。 线段树仍然只更新受影响的叶子，并且根一致地重新计算直径，而不需要结构重建。 

另一种情况是将非常早的“(”与非常晚的“)”交换。 这可以展平整个前缀和简档。 合并逻辑正确地捕获了这一点，因为它重新计算全局前缀最小值和最大值，因此直径在更新传播后立即减小。 

最后一种情况是重复交换以恢复原始字符串。 由于每次更新都是对称的，并且存储的节点中不存在历史依赖性，因此线段树自然地返回到初始状态。
