 ## 解决方案
 ## 问题理解

 我们得到一个源字符串`s`和一个目标字符串`t`， 在哪里`t` is already guaranteed to be a subsequence of `s`。 换句话说，我们可以从`s`以便并获得`t`无需重新排序任何东西。 

我们可以执行的操作是删除一个连续的字符块`s`。 删除该块后，我们想要`t`仍然保留结果字符串的子序列。 在删除块的所有有效选择中，我们希望删除尽可能长的段。 

任务的结构不是构建`t`再次强调，因为众所周知这是可以实现的。 真正的约束是确定哪个连续区间`s`是“安全擦除”，同时仍然保留至少一个有效的嵌入`t`。 

输入大小很小，每个字符串最多 200 个字符。 这立即排除了对后缀自动机或线段树等大量优化的需要。 三次甚至稍微二次的解是可以接受的，但是任何关于子串的指数`s`只有在仔细限制的情况下才仍然安全。 

当人们假设贪婪地删除不匹配项或尝试独立删除最长的前缀或后缀时，就会出现一种幼稚的失败模式。 例如，如果`s = "abacaba"`和`t = "aba"`，去掉中间的`"c"`是最优的，但是贪婪的前缀或后缀推理会错过它，因为两端都包含不同出现的基本匹配`t`。 

关键的困难是出现`t`可以通过多种方式嵌入内部`s`，并且删除中间段仍可能保留不同的嵌入。 

## 方法

 暴力方法会尝试所有可能的子字符串`[l, r]`删除。 对于每个选择，我们构造结果字符串并检查是否`t`仍然是一个子序列。 检查子序列需要线性时间`|s|`，所以这大致变成`O(n^3)`最坏的情况：`O(n^2)`子串次数`O(n)`后续检查。 和`n ≤ 200`，这是边界，但在 Python 中仍然安全； 然而，这是没有必要的。 

关键的观察是我们实际上不需要在删除后重建字符串。 相反，我们只需要知道是否可以分割嵌入`t`在`s`围绕已删除的段。 

考虑修复已删除的部分`[l, r]`。 如果`t`之后仍然是一个子序列，那么我们可以匹配一些前缀`t`在`s[0:l-1]`和剩余的后缀`t`在`s[r+1:]`。 所以问题就简化为寻找最佳分割`t`分为两个部分，可以作为前缀和后缀进行匹配`s`，位置尊重顺序。 

这导致预先计算两件事：对于每个前缀`s`, how much of `t`我们可以匹配，并且对于每个后缀`s`, 多少个后缀`t`我们可以匹配。 然后我们尝试所有分割点`s`，将它们解释为已删除线段的边界。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力删除+后续检查| O(n^3) | O(n^3) | O(n) | 已接受但没有必要 |
 | 前缀/后缀匹配 DP | O(n^2) | O(n^2) | O(n) | 已接受 |

 ## 算法演练

 我们构建两个数组。 第一个数组`pref[i]`存储多少个字符`t`我们可以只使用`s[0..i]`贪婪地从左到右。 第二个数组`suf[i]`存储多少个字符`t`我们可以只使用`s[i..n-1]`, but matching from right to left.

Then we interpret a removed segment `[l, r]`. If we remove it, we keep `s[0..l-1]`和`s[r+1..n-1]`。 假设我们匹配`k`的字符`t`在前缀部分，其余部分`|t|-k`在后缀部分。 我们需要确保这两个部分能够以一致的立场共存。 

我们使用这样的想法：对于每个前缀匹配长度`k`，我们知道最早的索引`s` where it ends, and for suffix match we know the latest index where it starts. We precompute forward and backward match positions.

A cleaner implementation uses two pointers:

1. Compute `pre[i]`作为最大前缀`t`匹配于`s[0..i]`。 
2. 计算`suf[i]`作为最大后缀`t`匹配于`s[i..n-1]`。 
3.对于每一个`l`在`s`，将其视为删除的开始。 
4. 对于每一个`r >= l`，计算是否存在分割`t`这样前缀就适合之前`l`后缀适合`r`。 
5. 跟踪最大值`r - l + 1`。 

这是有效的，因为任何有效的解决方案都对应于在有效的前缀匹配和后缀匹配之间切掉中间段`t`。 

### 为什么它有效

 任何有效的嵌入`t`最终字符串中的每个字符必须分配`t`到已删除段的左侧部分或右侧部分。 由于剩余的字符串保留顺序，因此左侧部分必须匹配前缀`t`在`s[0..l-1]`正确的部分必须匹配后缀`t`在`s[r+1..n-1]`。 该算法通过前缀和后缀匹配数组隐式枚举此前缀后缀划分的所有可能的分割点，确保不会错过任何有效的分割。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()
    n, m = len(s), len(t)

    # pref[i]: max prefix length of t matched in s[0:i]
    pref = [0] * n
    j = 0
    for i in range(n):
        if j < m and s[i] == t[j]:
            j += 1
        pref[i] = j

    # suf[i]: max suffix length of t matched in s[i:]
    suf = [0] * n
    j = m - 1
    for i in range(n - 1, -1, -1):
        if j >= 0 and s[i] == t[j]:
            j -= 1
        suf[i] = m - 1 - j

    # We also need boundary convenience
    pref_pos = [0] * n
    j = 0
    for i in range(n):
        if j < m and s[i] == t[j]:
            j += 1
        pref_pos[i] = j

    ans = 0

    # try all deletion intervals
    for l in range(n):
        for r in range(l, n):
            # check if we can split t into prefix+suffix
            # prefix from [0..l-1], suffix from [r+1..]
            # compute prefix match in prefix region
            k = 0
            for i in range(l):
                if k < m and s[i] == t[k]:
                    k += 1

            # compute suffix match in suffix region
            p = m - 1
            for i in range(n - 1, r, -1):
                if p >= 0 and s[i] == t[p]:
                    p -= 1

            if k > m - 1 - p:
                ans = max(ans, r - l + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```该实现直接测试每个可能的删除间隔。 对于每个间隔，它重新计算有多少个字符`t`左右两侧均可搭配。 条件比较分割是否覆盖了所有字符`t`没有重叠。 尽管这不是最优化的形式，但对于给定的约束来说它是正确且充分的。 

关键的微妙之处在于必须按时间间隔重新计算前缀和后缀匹配，这是可以接受的，因为`n ≤ 200`。 更优化的版本将重用预先计算的数组，但该版本优先考虑正确性的清晰度。

 ## 边缘情况

 一个微妙的情况是当`t`可以在里面以多种重叠的方式进行匹配`s`。 例如，`s = "aaaaa"`和`t = "aa"`。 该算法通过有效地允许任意两次出现的情况之间的分割来处理这个问题`a`，因为可以为每个删除间隔重新计算前缀和后缀匹配。 这确保删除中间块不会错误地消除替代嵌入。 

另一种情况是最佳删除从所选嵌入的两端删除字符。 例如，如果`s = "cababc"`和`t = "abc"`, the optimal deletion may sit in the middle and force `t`使用与字典顺序上的第一个完全不同的嵌入。 该算法仍然是正确的，因为它不承诺单个嵌入`t`, and instead recomputes feasibility for every split induced by the deletion interval.
