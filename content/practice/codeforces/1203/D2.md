 ## 解决方案
 ## 问题理解

 我们有两个字符串，`s`和`t`。 第二个字符串保证已经作为子序列出现在第一个字符串中，这意味着我们可以从中选取字符`s`以便并获得`t`。 

任务是从其中删除一个连续的段`s`这样删除后，`t`仍然可以作为剩余字符串的子序列获得。 在所有有效删除中，我们希望删除的段的最大可能长度。 

所以从概念上讲，我们正在寻找一个“洞”`s`：我们切出一个连续的块，我们需要剩下的左右部分仍然包含所有字符`t`为了。 

这些限制允许两个字符串最多包含 200,000 个字符。 任何尝试所有子字符串的解决方案都需要检查 O(n²) 候选者，这太慢了，因为每次检查还需要子序列验证。 这促使我们采用 O(n log n) 或 O(n) 策略。 

当出现关键的微妙边缘情况时`t`非常小甚至是单个字符。 在这种情况下，通常可以删除几乎整个字符串，但前提是该字符至少有一次出现在已删除的段之外。 例如，如果`s = "aaaaa"`和`t = "a"`，我们可以删除除一个位置之外的任何连续块，因此答案变为 4。 

另一个极端情况是当发生以下情况时`t`里面紧紧地包裹着`s`。 然后任何与所有有效嵌入重叠的删除`t`失败，即使它在本地看起来很大。 

## 方法

 暴力方法会尝试每对索引`l`和`r`， 消除`s[l:r]`，然后检查是否`t`仍然是剩余字符串的子序列。 该段有 O(n²) 个选择，并且后续检查成本为 O(n)，因此这变成了 O(n³)，即使对于中等输入大小也是不可行的。 

我们可以通过观察不需要为每次删除完全重新检查子序列来改进。 相反，我们想知道我们可以将左右部分之间的分割“推”多远，同时仍然能够匹配`t`。 

关键的想法是修复多少`t`从前缀开始匹配`s`，以及后缀的多少。 如果我们知道第一个`i`的字符`t`可以在前缀中匹配`s`，以及剩余的后缀`t`可以在后缀中匹配`s`，那么这两个匹配区域之间的所有内容都可以被删除。 

所以我们预先计算两个结构： 中的最早位置`s`其中前缀`t`结束，以及最新职位`s`其中后缀为`t`开始。 然后我们尝试所有的分割`t`分为前缀和后缀。 

这将问题简化为使用两个指针进行线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(1) | O(1) | 太慢了 |
 | 前缀后缀匹配 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 构建数组`pref[i]`意思是最早的索引`s`我们可以在哪里匹配前缀`t[0:i]`。 我们扫描`s`从左到右，将指针向前推进`t`每当字符匹配时。 这保证了我们总是尽早匹配，并在右侧留下最大的空间。 
2. 构建数组`suf[i]`意思是最新的索引`s`我们可以在哪里匹配后缀`t[i:]`。 我们扫描`s`从右到左，同样贪婪地匹配`t`从最后。 这可确保后缀尽可能正确地打包。 
3. 将答案初始化为 0。我们将删除两个位置之间的一段解释为`s`。 
4. 对于每个分割点`i`在`t`，将其解释为取前缀`t[0:i]`从左侧`s`，和后缀`t[i:]`从右侧`s`。 
5.如果前缀`t[0:i]`可以匹配到结束位置`pref[i-1]`，和后缀`t[i:]`可以从位置开始匹配`suf[i]`，那么我们可以严格删除这两个位置之间的所有内容。 
6、可拆卸长度为`suf[i] - pref[i-1] - 1`。 跟踪所有有效分割的最大值。 
7. 还要考虑我们采用空前缀或空后缀的情况`t`，对应于删除前缀或后缀`s`。 

### 为什么它有效

 建筑迫使每一个角色`t`分配给已删除段的左侧或右侧。 贪婪的前缀和后缀匹配确保如果分割在任何地方都是可行的，那么它在这些极值位置也是可行的。 任何有效的删除都对应于某个分区`t`分成两个子序列，算法检查所有这些分区，同时最小化重叠`s`，这使得可移动间隙最大化。

 ## 边缘情况

 当`t`只有一个字符，解决方案必须正确允许删除除一次出现之外的所有内容。 幼稚的方法可能会错误地假设我们需要保留多个匹配项周围的结构，但拆分逻辑自然会处理空前缀或后缀。 

什么时候`s`包含许多重复的字符，贪婪匹配必须始终优先选择最早和最新的位置。 如果匹配不是极值，则计算出的可移动段会人为收缩。 前缀-后缀结构保证最大间隙。 

什么时候`t`与`s`，每个有效的分割都会折叠到零可移除长度，因为前缀和后缀位置重合。 公式`right_pos - left_pos - 1`在所有情况下自然都会产生 0。
