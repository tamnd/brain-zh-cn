 ## 解决方案
 ## 问题理解

 每个项目都可以被视为只有当波利卡普的当前评级足够高时才可用的行动。 一旦他开始一个项目，他的评级可能会上升或下降，但决不允许在任何时候变成负面的。 我们的目标不是最大化评级，而是选择尽可能多的项目并为它们找到一些有效的执行顺序，以便每个选定的项目都可以在满足其要求时启动。 

困难在于项目不是独立的。 完成一个项目会改变评级，从而改变其他项目随后变得可行。 一个要求低但负奖励大的项目如果能够支持许多其他项目，那么它仍然可以作为垫脚石。 相反，如果一个高回报项目阻碍了对更好序列的访问，那么它可能无法使用。 

这些约束足够小，理论上可以对子集进行直接指数搜索，但完全不切实际。 对于多达 100 个项目，基于子集的方法已经给出了$2^{100}$可能性，并且每种可能性都需要检查有效的排序，这远远超出了任何可行的计算。 

仅基于按要求或奖励排序的贪婪策略也会失败。 一个在本地看起来很糟糕的项目可能需要稍后才能解锁其他项目。 同样，始终首先考虑最小的需求可能会使评级陷入这样的状态：即使不同的早期排序可以发挥作用，但没有剩余项目可用。 

当低要求项目产生较大负面影响时，就会出现微妙的失败案例。 太早采取可能会使未来的项目无法实现，即使跳过它会允许更大的总集。 当一个高要求的积极项目被不必要地推迟时，就会出现另一种失败模式，从而阻止访问它，即使它本来可以尽早使用。 

## 方法

 暴力的观点是尝试项目的所有子集，并检查是否存在使评级始终保持非负值的排序。 对于每个子集，可以模拟所有排列，但即使忽略排列，仅检查可行性就已经取决于排序决策。 和$n = 100$，子集的数量是$2^{100}$，甚至对每个子集进行恒定时间可行性检查也是不可能的。 

关键的观察是我们不需要在全球范围内修复完整的订单。 相反，我们可以在保持可行性的同时贪婪地构建偏序。 在任何时刻，在当前评级满足要求的所有可用项目中，我们希望选择一个使系统处于“最灵活”状态的项目。 

这导致了一个标准的转换：根据项目的效果将项目分为两种类型。 提高评级的项目一旦可用，本质上就是安全的，因为它们只会提高未来的可行性。 降低评级的项目是危险的，必须谨慎处理，因为它们会减少未来的选择。 

该结构提出了一种贪婪的优先策略：只要有可能，总是采取所有安全（非负收益）项目，并在有风险的项目中，仔细选择对未来可行性影响最小的项目。 为了正式化这一点，我们按照需求的递增顺序处理项目，维护可用项目的优先级队列。 积极的项目会立即进行，而消极的项目则以保留获得更困难的未来项目的能力的方式进行选择。 

本质上的减少是我们永远不需要重新考虑已经选择的项目。 一旦一个项目符合资格并被最佳采用，其效果将完全纳入当前评级，并且不再参与竞争。

 ## 算法演练

 我们根据项目的要求对项目进行排序$a_i$。 这确保了随着评级的增长，新项目将以受控和单调的方式提供。 

我们对当前满足但尚未采用的所有项目维护最大堆（优先级队列）。 堆的顺序是$b_i$，优先考虑能够带来最大直接利益的项目。 

我们还维护一个指向已排序项目列表的指针，一旦新解锁的项目变得可行，就会不断将其添加到堆中。 

该算法进行如下：

 1. 初始化电流额定值为$r$，将答案设置为零，并对项目进行排序$a_i$。 

排序使项目可用性与评级增长保持一致，以便我们可以逐步解锁它们。 
2. 按升序浏览项目$a_i$，将每个要求最多为当前评级的项目推入由以下键控的最大堆中$b_i$。 

该堆代表我们当前允许尝试的所有项目。 
3. 如果堆为空并且无法添加新项目，则停止该进程。 

此时，在当前评级状态下，没有剩余项目可到达。 
4.提取最高的项目$b_i$从堆中取出并执行它。 提高评级$b_i$并增加答案。 

选择最佳的即时收益可确保当存在更好的选择时，我们不会不必要地降低未来的灵活性。 
5. 执行项目后，重复扫描步骤，因为提高的评级可能会解锁新项目。 

排序效应至关重要：即使项目有负面影响$b_i$，如果它是最佳可用选项，仍然可以选择它。 然而，堆确保我们尽可能推迟这些有害的选择，转而选择有益的选择。 

保持不变的是，在每一步中，在所有当前可行的项目中，我们总是选择在直接评级影响方面限制最少的项目，同时从不违反需求约束。 这保证了如果一个项目可以成为某个最佳解决方案的一部分，那么它就不会被过早地排除，而不会迫使人们做出更糟糕的选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, r = map(int, input().split())
    projects = []
    for _ in range(n):
        a, b = map(int, input().split())
        projects.append((a, b))
    
    projects.sort()
    
    import heapq
    
    i = 0
    cur = r
    heap = []
    ans = 0
    
    while True:
        while i < n and projects[i][0] <= cur:
            heapq.heappush(heap, -projects[i][1])
            i += 1
        
        if not heap:
            break
        
        b = -heapq.heappop(heap)
        
        if cur + b < 0:
            continue
        
        cur += b
        ans += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```该实现依赖于按需求排序，以便增量地处理可行性。 堆存储被否定$b_i$值来模拟最大堆，确保我们始终首先考虑最有利的项目。 

支票`cur + b < 0`防止无效执行导致评分低于零。 这种保障措施是必要的，因为即使一个项目在要求上是可行的，但其效果仍然可能违反全局约束。

 ## 边缘情况

 当早期的负面项目可用但没有必要时，就会发生常见的失败案例。 天真的贪婪者可能会过早地接受它们，从而降低评级并阻止访问以后有益的项目。 基于堆的排序会延迟此类决策，直到不存在更好的替代方案。 

另一种边缘情况是，除了具有负面影响的项目外，最初没有任何项目可行。 该算法必须确保仅在该项目是唯一选择时才采用该项目，这是通过在每次评级更新后重复检查可用性来保证的。
