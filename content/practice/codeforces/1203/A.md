 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 在每个场景中，一组学生按固定的圆形顺序排列，我们将该顺序显示为表示绕圆圈顺时针遍历的线性列表。 

每个学生都有一个从 1 到 n 的唯一标签，给定的数组描述了当我们顺时针绕圆圈走时每个位置出现哪个标签。 

任务是确定这种圆形排列是否可以解释为任一方向的“完美连续舞蹈”。 在一种有效的情况下，从某个学生开始，顺时针移动应该会按顺序产生序列 1, 2, 3, ..., n，不间断。 在另一种有效情况下，顺时针移动应该产生相反的序列 n, n−1, ..., 1。由于圆没有固定的起点，因此我们可以旋转序列，但不允许重新排序。 

因此，问题简化为检查给定的循环排列是否是递增序列或递减序列的旋转。 

约束很小，n 最多 200，q 最多 200。这意味着即使是检查每次旋转或直接检查每个位置的解决方案也很容易足够快。 每个测试用例进行线性扫描就足够了。 

当 n 等于 1 或 2 时，会出现微妙的边缘情况。对于 n = 1，任何排列都是有效的。 对于 n = 2，[1, 2] 和 [2, 1] 都有效，但像 [1, 1] 这样的重复是不可能的，因为输入保证是排列，因此有效性仅取决于邻接一致性。 

一个常见的错误是只检查相邻差异是+1还是-1而不考虑环绕一致性。 例如，即使 1 在索引顺序上与 2 不相邻，[2, 3, 4, 5, 1] 也是有效的； 圆形包装使其有效。 

## 方法

 思考这个问题的一种蛮力方法是尝试循环中每一个可能的起点。 对于每个起始索引 i，我们模拟顺时针行走并检查是否可以按顺序读取 1 到 n，或者按顺序读取 n 到 1。 这需要每个起始点进行 O(n) 工作，每个测试用例的时间复杂度为 O(n^2)。 

虽然这对于 n ≤ 200 来说已经是可以接受的，但我们可以使用一个关键观察进一步简化：在有效的排列中，如果我们沿着圆顺时针移动，连续元素之间的差必须始终一致 +1（值空间中的 mod n）或一致 -1（值空间中的 mod n）。 结构是刚性的：一旦我们确定了方向，整个排列就确定了。 

因此，我们不尝试所有旋转，而只检查所有相邻差异在循环解释时是否与递增一或递减一一致。 

我们可以通过检查每个位置 p[i+1] 是否是 p[i]+1（或从 n 到 1），或者 p[i+1] 是 p[i]−1（或从 1 到 n）来实现这一点。 如果任一条件适用于所有边（包括最后一个到第一个边），则答案为“是”。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力旋转检查 | O(n^2) | O(n^2) | O(1) | O(1) | 已接受 |
 | 方向一致性检查 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 读取当前查询的排列，代表绕圆的顺时针顺序。 这个顺序是固定的，不能修改。 
2. 假设我们尝试验证顺时针递增序列。 我们验证每个连续的对是否遵循值恰好增加 1 的规则，特殊情况是 n 连接回 1。 
3. 如果递增检查失败，请尝试递减版本，其中每个步长必须恰好递减 1，特殊情况是 1 连接回 n。 
4. 对于这两项检查，我们必须将序列视为循环，这意味着最后一个元素连接回第一个元素。 这确保我们测试的是完整的循环而不是断线。 
5. 如果任一方向对于每个相邻对都有效，则输出 YES。 否则输出NO。 

### 为什么它有效

 一种有效的圆形舞蹈要求绕圈行走始终在一个一致的方向上产生连续的标签。 这强制实施了一项全局约束：每个节点在遍历方向上都只有一个有效的后继节点。 因为标签是一种排列，即使有一个邻接违反了+1或-1规则，也不可能将圆旋转成完美的序列。 相反，如果所有邻接都满足两个一致步骤规则之一，则整个循环必须形成按顺序覆盖所有整数的单个有向循环。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ok_inc(p):
    n = len(p)
    for i in range(n):
        cur = p[i]
        nxt = p[(i + 1) % n]
        if cur == n:
            if nxt != 1:
                return False
        else:
            if nxt != cur + 1:
                return False
    return True

def ok_dec(p):
    n = len(p)
    for i in range(n):
        cur = p[i]
        nxt = p[(i + 1) % n]
        if cur == 1:
            if nxt != n:
                return False
        else:
            if nxt != cur - 1:
                return False
    return True

q = int(input())
for _ in range(q):
    n = int(input())
    p = list(map(int, input().split()))
    if ok_inc(p) or ok_dec(p):
        print("YES")
    else:
        print("NO")
```该代码将两个可能的有效结构分为两个显式检查。 每个函数都会遍历循环排列的所有边，并验证后继关系是否与严格的算术级数模 n 匹配。 

使用模索引`(i + 1) % n`至关重要，因为最后一个元素必须连接回第一个元素，否则我们只会验证路径而不是循环。 

## 工作示例

 ### 示例 1：p = [1, 2, 3, 5, 4]

 我们首先测试增加方向。 

| 我| 当前| 下一个 | 预计 | 至今有效 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 2 | 2 = 1+1 | 是 |
 | 1 | 2 | 3 | 3 = 2+1 | 是 |
 | 2 | 3 | 5 | 预计 4 | 否 |

 递增检查在从 3 过渡到 5 时失败。然后我们测试递减顺序。 

| 我| 当前| 下一个 | 预计 | 至今有效 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 2 | 0 预期换行 | 立即不 |

 两个方向都不起作用，因此输出为 NO。 

这表明单个损坏的邻接足以使整个循环失效。 

### 示例 2：p = [3, 2, 1, 4]

 增加检查：

 | 我| 当前| 下一个 | 预计 | 有效 |
 | --- | --- | --- | --- | --- |
 | 0 | 3 | 2 | 预计 4 | 否 |

 减少支票：

 | 我| 当前| 下一个 | 预计 | 有效 |
 | --- | --- | --- | --- | --- |
 | 0 | 3 | 2 | 2 = 3−1 | 2 = 3−1 | 是 |
 | 1 | 2 | 1 | 1 = 2−1 | 1 = 2−1 | 是 |
 | 2 | 1 | 4 | 4 = 1−1 换行 | 是 |
 | 3 | 4 | 3 | 3 = 4−1 | 3 = 4−1 | 是 |

 这证实了有效序列不需要从 1 开始； 完美递减循环的任何旋转都是可以接受的。

 ## 边缘情况

 对于 n = 1，两项检查都会成功，因为没有任何转换会违反一致性，因此单个学生根据定义形成了一个有效循环。 

对于像 n = 2 这样的小循环，两个方向都会陷入相同的邻接检查，并且算法正确地接受 [1, 2] 和 [2, 1]，因为每个方向都满足严格的后继规则之一。 

对于 [3, 4, 5, 1, 2] 等旋转，即使序列不是从 1 开始，递增检查也会成功。数组末尾的模条件确保环绕正确性，确认结构是真正的圆形而不是线性。
