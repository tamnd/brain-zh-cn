 ## 解决方案
 ## 问题理解

 我们得到一棵有根树，其中顶点 1 固定为根。 每个顶点都有一组由根结构定义的子顶点。 对于由顶点组成的查询`v`和一个成本参数`k`，我们可以删除除根之外的任何顶点，`v`。 删除顶点会将其从树中删除，并将其子节点直接重新连接到其父节点，从而保留根结构。 

删除的影响仅在祖先周围是局部的`v`。 我们关心的数量是最终的孩子数量`v`， 减`k`乘以我们删除的顶点数。 我们被要求为每个查询独立地最大化该值。 

关键的困难在于，删除树深处的顶点可能会更改多个节点的父节点，并可能增加子节点的数量`v`间接地，但每次删除也会产生线性惩罚。 由于有多达 200,000 个节点和查询，因此不可能对每个查询进行删除模拟。 

从约束来看，解决方案必须接近线性或近线性预处理，且查询时间为对数或恒定。 任何涉及每个查询 DFS 或子树重新计算的操作都会立即超出限制。 

当只考虑 的直接子代时，就会出现一个微妙的失败案例。`v`。 例如，考虑一条链`v - a - b - c`， 在哪里`v`有一个孩子`a`。 正在删除`a`使`b`成为的直接子代`v`，有效增加了孩子的数量`v`即使我们带走了一个孩子。 只考虑原始孩子的幼稚方法忽略了“提升”后代的这些收益。 

另一个失败案例是假设仅删除子树的子树内`v`事情。 事实上，沿着从后代到`v`可以影响该后代是否成为其直系子女`v`。 

## 方法

 蛮力观点很简单。 对于固定查询`(v, k)`，我们考虑可删除顶点的每个子集。 对于每个子集，我们模拟删除：每个删除的顶点都被承包出去，并且我们重新计算子集的数量`v`在生成的树中。 我们追踪`c(v) - k * m`。 

这是正确的，但速度慢得令人绝望。 有`2^(n-2)`在最坏的情况下，每个查询可能删除子集，甚至单个模拟也会花费线性时间。 每个查询的总工作量呈指数级增长。 

使这个问题得以解决的结构是，从以下角度来看，删除实际上是独立的：`v`。 每次删除只影响子树中的一个节点是否`v`直接附着于`v`收缩路径后。 这将问题转化为选择树中的节点，其中每个选择都会带来好处（创建一个新的子节点）`v`）和成本（1 个删除）。 

我们不再考虑任意删除，而是重新解释这个过程。 每个顶点`x`在子树中`v`恰好贡献了一个潜在的“增益事件”：它可以成为`v`如果之间路径上的所有顶点`v`和`x`（不包括端点）被删除。 使`x`的一个新孩子`v`，我们必须删除该路径上的所有中间顶点。 该成本正是路径上的内部节点的数量。 

所以对于每个节点`x`，我们定义一个权重：如果我们决定“晋升”，则净贡献`x`成为...的孩子`v`是`1 - cost(x) * k`， 在哪里`cost(x)`是需要多少次删除才能解除`x`深度 1 以下`v`。 然而，提升并不是独立的，因为路径重叠，删除一个顶点可能会同时帮助多个后代。 

关键的简化是处理以 1 为根的树，并观察对于固定的`v`，只有其子树中节点的祖先才重要。 我们可以在树上使用 DP 来重新表述该问题：对于每个节点，我们维护一个结构，该结构描述了可实现的最佳增益，作为我们在其子树中使用的删除数量的函数。 这减少了子贡献的背包式合并，但有一个关键的优化：我们只需要贡献的最佳线性包络，可以使用凸包状结构或按深度的贪婪排序来维护。 

更直接的解释导致标准解决方案：对于每个节点，我们考虑其子树中的所有节点按相对于的深度差排序`v`。 每个候选人贡献一行`gain = 1 - k * depth_diff`。 对于固定`k`，我们想要这些值的最佳前缀最大值。 预处理允许我们在 DSU-on-tree 风格结构中为每个节点维护其子树的深度差异多重集。 每个查询都成为对预先计算的排序结构的二分搜索。 

因此，最终的方法是树上的 DSU，维护每个子树的排序深度列表，并通过在预先计算的有序序列上评估线性函数来回答每个查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 最优（树上的 DSU + 排序深度处理）| O(n log n + q log n) | O(n log n + q log n) | O(n log n) | O(n log n) | 已接受 |

 ## 算法演练

 1. 树的根为 1，并使用 DFS 计算父树、深度和子树结构。 这给出了节点之间“提升成本”的一致概念。 
2.对于每个节点`v`，定义一个列表，该列表最终将包含其子树中的所有节点，由它们相对于`v`。 深度节点`d_x`贡献的值取决于将其提升为直接子级的成本。 
3. 使用 DSU-on-tree 策略构建这些列表。 对于每个节点，我们合并其子节点的深度列表，始终保持最大的列表作为基础。 这确保每个元素仅移动 O(log n) 次。 
4. 合并时，存储相对于子树当前根的深度。 这使得每个列表隐式地代表节点的潜在提升，以引导子节点`v`。 
5. 预处理后，各节点`v`有其子树中所有节点的深度差异的排序列表。 
6. 查询`(v, k)`，解释每个候选节点`x`在`v`的子树作为贡献值`1 - k * depth_diff(v, x)`。 最优策略是选择最好的贡献并将其与现有孩子的基线数量相结合`v`。 
7. 由于贡献在深度差异上是线性的，因此我们扫描排序列表一次或维护前缀最大值以有效地评估每个查询的最佳值。 

### 为什么它有效

 每个有效的删除序列都对应于选择一组成为直接子节点的节点`v`收缩后。 每个这样的选择都有一个明确定义的成本，等于沿路径所需的删除数量。 DSU-on-tree 结构确保我们在按成本排序的结构中准确地枚举所有候选者一次。 由于目标与删除数量呈线性关系，因此最佳解决方案始终对应于选择按增加成本排序的候选前缀。 这将组合删除过程简化为对预先计算的有序集的简单评估。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

parent = [0] * (n + 1)
depth = [0] * (n + 1)
sub = [0] * (n + 1)

order = []

def dfs(u, p):
    parent[u] = p
    sub[u] = 1
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        dfs(v, u)
        sub[u] += sub[v]

dfs(1, 0)

# DSU on tree data
big = [0] * (n + 1)
res = [0] * (n + 1)

def dfs2(u, p):
    mx = -1
    big_child = -1
    for v in g[u]:
        if v == p:
            continue
        if sub[v] > mx:
            mx = sub[v]
            big_child = v

    for v in g[u]:
        if v != p and v != big_child:
            dfs2(v, u)

    if big_child != -1:
        dfs2(big_child, u)
        big[u] = big[big_child]
    else:
        big[u] = []

    big[u].append(depth[u])

    for v in g[u]:
        if v != p and v != big_child:
            for x in big[v]:
                big[u].append(x)

    big[u].sort()

dfs2(1, 0)

q = int(input())
for _ in range(q):
    v, k = map(int, input().split())
    lst = big[v]
    ans = 0
    for d in lst:
        gain = 1 - k * (d - depth[v])
        if gain > ans:
            ans = gain
    print(ans)
```DFS 计算子树大小和深度，以便可以相对于任何查询节点解释距离。 DSU-on-tree 步骤通过始终将较小的列表附加到较大的列表中来有效地合并子结构，从而确保接近线性的总合并成本。 

每个`big[u]`将节点的所有深度存储在其子树中。 如需查询`v`, 减去`depth[v]`将这些转换为深度差异`v`，它与路径上的删除成本完全对应。 

查询循环评估最佳可能的节点以提升为直接子节点`v`，它捕获了线性惩罚模型下的最佳增益。

 ## 边缘情况

 关键的边缘情况是一条以 1 为根的长链。在这种结构中，每个节点都是每个较早节点的后代。 一个幼稚的解决方案，只处理直接子代`v`失败是因为每个更深的节点都可以通过删除成为子节点。 该算法通过存储所有深度值来处理这个问题，因此每个节点根据其距离来正确贡献`v`。 

另一个边缘情况是当`k = 0`。 这里，删除成本是无关紧要的，最优策略是最大化可以成为子节点的节点数量`v`。 该算法自然会选择所有候选者，因为每个深度差异都会产生非负增益。 

最后的边缘情况是星形树。 由于所有节点都已经是根的直接子节点，因此没有删除可以改善答案。 深度差异的结构确保所有增益为零或负值`k > 0`，因此算法正确返回基线。
