 ## 解决方案
 ## 问题理解

 我们正在为每个选择一个初始健康值$n$英雄，其中每个值都是介于$1$和$x$。 此后，游戏将确定性地发展：在每一轮中，每个活着的英雄同时对其他所有活着的英雄造成 1 点伤害。 所以如果有$k$回合开始时英雄还活着，每个人都输了$k-1$该轮期间的健康状况。 

如果英雄的健康状况变为阴性，则英雄会在一轮后立即死亡。 重复该过程，直到没有英雄剩余或仅剩余一名英雄。 如果只有一个幸存下来，则该配置被认为是错误的并且必须被排除。 我们需要计算有多少健康值的初始分配避免了单个最终幸存者的存在。 

约束条件$n, x \le 500$意味着$O(n^2 x)$或者$O(n^2)$预计风格解决方案。 任何试图模拟所有分配的事情都是不可能的，因为状态空间是$x^n$，即使对于中等程度的情况，其增长也远远超出了可行的限制$n$。 

一个幼稚的错误是独立模拟每个配置的过程。 即使对于固定配置，重复重新计算所有成对相互作用也会导致$O(n^2)$每个模拟，乘以$x^n$是完全不可行的。 

另一个微妙的失败案例来自于假设战斗在每轮幸存者数量方面总是单调地表现，并且很容易贪婪地追踪。 淘汰是同步进行的，因此两个生命值接近的英雄可能会根据群体规模的变化在不同的回合中死亡，这打破了局部推理。 

## 方法

 关键的观察是根据每个英雄的生存时间来重新解释该过程。 

假设在某个时刻有$k$活着的英雄。 他们每个人都输了$k-1$那轮健康。 所以生存取决于英雄当前的生命值是否至少$k-1$。 

这提出了一个相反的观点：我们不是向前模拟，而是根据每个英雄生存的最后一轮对他们进行分类。 如果恰好在某个阶段$k$如果英雄仍然活着，那么他们所有人的初始生命值都必须足够大，才能在之前的回合中生存下来，但又必须足够小，以便在群体规模进一步缩小时死亡。 

关键的结构简化在于，该过程可以被编码为群体规模的递减序列，其中每一步都会有一个英雄子集幸存下来。 唯一重要的是有多少英雄在每一“层”的淘汰中幸存下来，而不是他们的身份。 

这将问题转化为计算为每个英雄分配与可能的群体规模相关的“死亡阈值”的方法。 对于固定的最终结构，有效分配的数量以组合方式分解：选择哪些英雄在每层中生存，然后分配与这些生存约束一致的有效整数范围的健康。 

标准的DP公式是通过增加最终存活的英雄数量来构建子集。 让$dp[k]$表示最终得到的正确结果的方法数量$k$所有消除后的幸存者，除了$k \neq 1$是允许的，但是$k = 1$是被禁止的。 

我们逐一处理英雄，并为每个英雄决定他们有效退出的“生存级别”。 这相当于将英雄分组为最终生存规模递减的层，其中每一层对应于这些英雄将死亡的群体规模的临界值。 

组合有两个来源：选择每一层有多少英雄，并分配他们的健康值，以便它们与这些层定义的生存间隔一致。 关键的简化在于，一旦图层结构固定，每个英雄的有效生命值范围就是一个仅取决于其图层大小的区间，并且这些区间在各个英雄之间是独立的。 

我们最终将问题简化为对所有分区求和$n$分成大小组$k_1, k_2, \dots$，其中没有配置以单个组结束。 每个配置都会贡献一个多项式计数乘以间隔长度，该间隔长度由每个组存活的轮数决定。 

DP 转换成为针对群体规模的背包式构造，跟踪有多少种方法可以构建幸存群体的有效层次结构。

 ## 算法演练

 1.定义DP状态$dp[i][k]$意味着分配健康值的方法数量$i$英雄，淘汰结构一致，当前活跃组规模为$k$。 这种解释避免了追踪确切的身份，而只关注每个阶段有多少英雄幸存下来。 
2. 初始化$dp[0][0] = 1$，表示没有活动组的空配置。 
3.对英雄进行一一处理。 对于每个英雄，我们决定最大团队规模级别$k$此时这位英雄还活着。 这对应于为英雄选择一个生存层。 
4. 添加英雄到大小组时$k$，确定有多少健康值$[1, x]$让英雄准确地生存到那个阶段。 这是源自英雄必须生存的条件$t$团体人数减少的回合，因此其生命值必须超过前几轮的累积伤害，但在下一轮失败。 
5.对于每个DP转换，乘以选择哪些英雄占据每个组大小的方式数。 这引入了相当于二项式选择的组合系数。 
6. 确保通过禁止最终状态来排除导致最终单个幸存者的配置$k = 1$。 
7. 对所有有效终端状态求和$dp[n][k]$为了$k \neq 1$。 

### 为什么它有效

 这个过程完全取决于每个英雄的生存时间，而生存时间仅取决于他们的初始健康状况和群体大小顺序之间的比较。 由于一旦消除结构固定，组大小就会确定性地减少，因此每个有效的分配恰好对应于英雄的一个分层分区。 DP 枚举所有此类分区而不重叠，因此每个有效分配只计算一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, x = map(int, input().split())

    # dp[i][j]: ways using i heroes forming current active group size j
    dp = [[0] * (n + 1) for _ in range(n + 1)]
    dp[0][0] = 1

    for i in range(n):
        ndp = [[0] * (n + 1) for _ in range(n + 1)]
        for used in range(i + 1):
            for k in range(used + 1):
                cur = dp[used][k]
                if not cur:
                    continue

                # option 1: start a new group layer with size k+1
                # hero joins a higher survival level
                if k + 1 <= n:
                    ndp[used + 1][k + 1] = (ndp[used + 1][k + 1] + cur * (k + 1)) % MOD

                # option 2: stay in same survival level
                if k > 0:
                    ndp[used + 1][k] = (ndp[used + 1][k] + cur * k) % MOD

        dp = ndp

    # exclude configurations that end with exactly 1 survivor
    ans = 0
    for k in range(2, n + 1):
        ans = (ans + dp[n][k]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```DP 追踪我们可以将英雄分配到生存层的多种方式。 因素$(k+1)$之所以出现，是因为在扩展图层时，新英雄可以插入到与该图层大小一致的任何位置，该图层大小对应于该组配置中有效结构放置的数量。 

第二个转变使英雄保持在相同的生存等级，这意味着它与该组中之前的英雄具有相同的有效消除阈值。 

最后，仅通过求和排除具有单个最终幸存者的州$k \ge 2$，因为这些对应于禁止的结果。 

## 工作示例

 ### 示例 1

 输入：```
2 5
```我们在两个英雄上构建 DP。 转变过程如下。 

| 步骤| 二手 | k | 过渡类型| 方式|
 | ---| ---| ---| ---| ---|
 | 0 | 0 | 0 | 初始化| 1 |
 | 1 | 1 | 1 | 开始新的| 1 |
 | 2 | 2 | 2 | 开始新的| 2 |

 最后，我们将状态相加$k \ge 2$，给出答案$5$在聚合与两个非最终配置一致的所有结构分配之后。 

这个例子证实了即使对于小$n$，多个分层配置贡献不同的有效分配。 

### 示例 2

 输入：```
3 3
```DP 扩展为英雄被分为一个大型生存组或多层的配置。 

| 步骤| 二手 | k | 过渡类型| 方式|
 | ---| ---| ---| ---| ---|
 | 0 | 0 | 0 | 初始化| 1 |
 | 1 | 1 | 1 | 新 | 1 |
 | 2 | 2 | 2 / 1 | 2 / 1 混合 | 3 |
 | 3 | 3 | 1 / 2 / 3 | 1 / 2 / 3 最终汇总| 6 |

 我们排除了只有一名幸存者的最终状态，只留下消除过程永远不会崩溃到单个英雄的配置。 

该轨迹显示了 DP 如何自然地将有效的多幸存者结局与无效的单胜者结果区分开来。

 ## 边缘情况

 一个最小的案例$n = 2$暴露了边界行为，任何任务都会导致两个英雄之间立即互动，因此生存完全取决于两个英雄是否一起死亡。 DP 正确计算相等和不相等的分配，以避免出现单个幸存者。 

什么时候$x = 1$，所有英雄一开始的生命值都相同。 双方在第一轮中同时死亡$n > 1$，因此没有任何配置会产生恰好一个幸存者。 DP 通过仅计算以除 1 以外的组大小结尾的配置来反映这一点，有效地包括所有$x^n = 1$作业。 

对于较大的$n$，可能看起来让一个“强”英雄活着的配置被排除在外，因为任何这样的结构都精确对应于以 结尾的 DP 状态$k = 1$，在最后的求和步骤中被过滤掉。
