 ## 解决方案
 ## 问题理解

 我们给出了一条规则，用从 1 开始的正整数填充无限网格。放置不会以简单的线性方式逐行或逐列进行。 相反，填充物以交替的垂直和水平“运行”移动，形成对角线状图案。 

该过程可以被认为是重复选择第一行上的下一个可用起始单元，然后尽可能向下移动，然后切换到沿同一行向左移动，直到到达第一列。 完成此 L 形扫描后，该过程从顶行的下一个空单元格重新开始。 

对于每个查询整数 k，我们需要确定包含 k 的单元格的行和列坐标。 

约束最多允许 100 个查询，k 可以大到 10^9。 这立即排除了任何构建网格甚至逐步遵循填充过程的模拟。 即使单个迹线达到 10^9 也会太慢，因为路径长度随 k 线性增长。 

一个天真的解释可能会尝试模拟填充过程直到达到 k，并跟踪坐标。 这在实践中是不正确的，不仅因为时间复杂性，而且因为运动结构在尺寸增长的块中改变方向，使得很容易错误计算垂直和水平阶段之间的过渡。 

第二个微妙的陷阱是在没有理由的情况下假设简单的对角枚举或三角形编号。 运动并不是严格意义上的经典意义上的对角线运动，因此如果从不正确的几何假设导出，像 k 这样属于三角形数层的公式将会失败。 

## 方法

 解决这个问题的关键是认识到数字的路径在网格对角线上形成可预测的之字形。 每个“层”对应于对角线和 r + c，该对角线和在运动段内保持恒定。 

如果我们仔细观察这个过程，就会发现数字按照系统顺序沿着对角线放置：首先增加行，减少列，然后切换方向。 这创建了一个结构，其中所有数字均按常数 r + c 的对角线有效分组，并且在每个对角线内，方向交替。 

蛮力方法将逐步模拟该过程，维持网格或至少跟踪当前位置和方向。 这在概念上是可行的，因为我们遵循确切的规则，但一旦 k 变大，它就变得不可行，因为在最坏的情况下我们需要 O(k) 次转换。 

解锁有效解决方案的洞察力是停止思考运动，而是通过对角线进行索引。 每条对角线都包含一个连续的数字块，直到对角线 d 的元素总数与 d(d+1)/2 成正比。 这将问题简化为查找 k 属于哪条对角线，然后定位该对角线内的偏移量。 

一旦确定了对角线，我们就可以使用算术而不是模拟来重建坐标。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 每次查询 O(k) | O(1) | O(1) | 太慢了 |
 | 对角线数学| 每个查询 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于给定的k，通过找到最小的d使得d(d+1)/2≥k来确定其所属的对角线层。 

这是可行的，因为对角线累积了三角形数量的元素。 
2. 计算 k 在该对角线内的位置，即 offset = k − d(d−1)/2。 

这给出了当前对角线内的索引。 
3. 根据对角线奇偶性确定坐标。 

如果 d 为奇数，则对角线从下到上填充，因此行随着偏移量沿对角线方向向下增加而增加。

如果 d 为偶数，则从上到下填充对角线，反转行和列角色的分配。 
4. 使用对角线结构将偏移量转换为 (r, c)：所有对都满足 r + c = d + 1。 
5. 输出计算出的(r,c)。 

### 为什么它有效

 在任何时刻，所有数字都按固定 r + c 的对角线分组。 在移动到下一个对角线之前，每个对角线都被完全填满。 对角线中直到 d 的元素总数形成一个三角形数，这保证了二分搜索或直接基于平方根的计算正确识别对角线。 在对角线内，交替方向是一致的并且仅取决于奇偶校验，因此从偏移到坐标的映射是确定性的。 这可以防止重叠或模糊，确保每个 k 恰好映射到一个单元格。 

## Python 解决方案```python
import sys
import math
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        k = int(input())

        d = math.isqrt(2 * k)
        while d * (d + 1) // 2 < k:
            d += 1
        while (d - 1) * d // 2 >= k:
            d -= 1

        prev = d * (d - 1) // 2
        offset = k - prev

        if d % 2 == 0:
            r = offset
            c = d + 1 - offset
        else:
            r = d + 1 - offset
            c = offset

        print(r, c)

if __name__ == "__main__":
    solve()
```该代码首先通过整数平方根近似并向上或向下校正来找到正确的对角线。 这避免了浮点精度问题并确保大 k 的正确性。 三角形前缀和给出了每条对角线的边界。 

一旦知道了对角线，我们就可以计算 k 距离它有多远。 然后奇偶校验确定我们是否沿一个方向或相反方向遍历对角线。 最终的坐标计算使用不变式 r + c = d + 1。 

一个常见的实现错误是当初始平方根估计超调时忘记向下调整对角线，这会导致偏移计算不正确以及最终坐标中的相差一误差。 

## 工作示例

 ### 示例 1：k = 5

 我们搜索 d 使得 d(d+1)/2 ≥ 5。 

| d | d(d+1)/2 | 上一个总和 | 偏移| 平价| r | c |
 | --- | --- | --- | --- | --- | --- | --- |
 | 2 | 3 | - | - | - | - | - |
 | 3 | 6 | 3 | 2 | 奇数| 2 | 1 |

 对角线 3 包含数字 4、5、6。该对角线中的第二个元素是 5，它映射到 (2,1)。 

这证实了对角线内的偏移映射与三角形分解一致。 

### 示例 2：k = 14

 找到 d，使得 d(d+1)/2 ≥ 14。由于 15 ≥ 14，我们得到 d = 5。 

| d | 前缀和| 偏移| 平价| r | c |
 | --- | --- | --- | --- | --- | --- |
 | 5 | 10 | 10 4 | 奇数| 2 | 3 |

 对角线 5 包含值 11 到 15。该对角线中的第四个元素是 14，映射到 (2,3)。 

这显示了较大的对角线如何在不改变逻辑的情况下保持相同的算术结构。

import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            k = int(input())
            d = math.isqrt(2 * k)
            while d * (d + 1) // 2 < k:
                d += 1
            while (d - 1) * d // 2 >= k:
                d -= 1
            prev = d * (d - 1) // 2
            offset = k - prev
            if d % 2 == 0:
                r, c = offset, d + 1 - offset
            else:
                r, c = d + 1 - offset, offset
            out.append(f"{r} {c}")
        return "\n".join(out)

    return solve()

 ## 边缘情况

 对于k = 1，算法识别d = 1，prev = 0，offset = 1，并直接输出(1,1)。 这证实了基本对角线已正确处理，无需任何校正。 

对于 k = 2，我们得到 d = 2，prev = 1，offset = 1。由于 d 是偶数，我们分配 r = 1，c = 2，匹配第二条对角线中的第二个单元格。 这验证了奇偶校验处理不会在最小的非平凡对角线上中断。 

对于较大的 k（例如 10^9），对角线索引 d 约为 31622。校正循环立即稳定，因为平方根估计已经非常接近。 这证实了即使在最大输入大小下，该算法在实践中仍保持恒定时间。
