 ## 解决方案
 ## 问题理解

 我们得到了一个起始数字，并限制了我们可以使用多少个不同的数字。 对于每个查询，我们必须找到不小于给定数字且最多使用十进制表示的最小整数`k`不同的数字。 

输出不是在本地转换输入数字，而是在整数中向前搜索，直到找到满足全局数字约束的第一个数字。 这使得该问题从根本上成为整数行上的受限后继搜索。 

约束以非常具体的方式严格。 的价值`n`可以达到$10^9$，所以数字最多有 10 位数字。 测试用例的数量可以大到$10^4$，这排除了任何尝试从`n`在最坏的情况下。 每个查询的线性扫描可能会退化为数十亿个数字的检查。 

一个天真的想法是从`n`向上，检查每个数是否最多使用`k`不同的数字。 这会失败，因为在我们到达有效数字之前，很长的数字可能会违反约束。 特别是，如果`k = 1`，像 100000000、100000001、100000002 等数字在我们达到 111111111 之前都是无效的。这个差距是巨大的。 

当出现第二个微妙的失败案例时`n`已经包含超过`k`不同的数字。 贪婪地尝试只“修复”第一个有问题的数字而不考虑全局传播很容易产生一个小于`n`或者错过真正的最小候选者。 

真正的挑战是数字限制与位置结构相互作用。 小的局部更改会传播到大的后缀更改。 

## 方法

 蛮力方法很简单：从`n`，检查每个数字，计算其不同数字，并在满足条件时停止。 每张支票费用$O(\log n)$，在最坏的情况下，我们可能会在达到有效数字之前扫描非常大的范围。 如果答案很远，那么在时间限制下这是不可行的。 

关键的观察是有效数字的结构在以下情况下受到极大限制：`k ≤ 2`。 最多使用两位数的数字必须完全由一位重复的数字或两位数字混合组成。 这意味着，一旦我们决定允许使用哪些数字，最佳候选者就不是任意的，它在字典顺序上受到数字选择和位置的限制。 

我们不再盲目地向前搜索，而是考虑逐位构建答案。 对于每个位置，我们尝试匹配前缀`n`，如果失败，我们向上调整该位置并使用最多使用最小的可能有效延续来填充后缀`k`数字。 

中心思想是基于前缀的数字动态规划，但由于以下事实而简化：`k`只有 1 或 2。我们枚举可能的数字集（大小 1 或 2），对于每个数字集，我们构建最小的数字 ≥`n`仅使用这些数字即可组成。 答案是所有此类结构中的最小值。 

因为最多有 10 位数字，而我们只选择 1 位或 2 位数字的集合，因此候选数量很少，足以进行暴力破解。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(t \cdot \Delta \cdot \log n)$在哪里$\Delta$可以很大|$O(1)$| 太慢了|
 | 最佳|$O(t \cdot 10^2 \cdot 10)$|$O(1)$| 已接受 |

 ## 算法演练

 我们独立处理每个测试用例并构造最佳有效数字。 

1. 提取所有候选数字集。 

我们枚举所有大小为 1（10 种可能性）和大小 2（45 种可能性）的集合。 这是可行的，因为数字范围仅从 0 到 9。 
2. 对于每个候选数字集，尝试构造不小于的最小数字`n`。 

我们代表`n`作为处理逐位构造的字符串。 
3.对于固定的数字集，我们尝试匹配`n`从左到右。 

在每个位置，我们尝试放置不违反前缀约束的最小允许数字。 
4. 如果我们可以在数字集中匹配整个前缀，我们就接受这个结构作为候选答案。 
5. 如果在某个位置我们无法匹配`n`确切地说，我们通过选择下一个较大的允许数字来“打破”前缀，并用最小的允许数字填充剩余位置。 

这一步至关重要，因为一旦我们超过`n`在某个位置上，应贪婪地最小化其余数字。 
6. 如果一个数字集不能产生相同长度的数字 ≥`n`，我们尝试长度最小的有效数字`len(n) + 1`，这只是使用该数字集的最小非零前导结构。 
7. 取所有有效结构中的最小值。 

### 为什么它有效

 正确性来自于以下事实：任何有效答案都必须对应于大小最多为 2 的数字集的某种选择。一旦数字集固定，满足约束且 ≥ 的最小数字`n`由贪婪的字典结构决定。 任何与贪婪选择的偏差都会使数字小于`n`或者不必要地增加它，因此它不是最佳的。 穷尽所有数字集可以保证我们不会错过最佳配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_with_set(s, digits):
    digits = sorted(digits)
    n = len(s)

    # try same length
    res = None

    for i in range(n):
        ok = False
        for d in digits:
            if i == 0 and d == 0:
                continue
            if d > s[i]:
                cand = []
                cand.extend(list(s[:i]))
                cand.append(str(d))
                cand.extend([str(digits[0])] * (n - i - 1))
                cand_str = ''.join(cand)
                if res is None or cand_str < res:
                    res = cand_str
                ok = True
                break
            elif d == s[i]:
                ok = True
                break

        if not ok:
            break
    else:
        # fully matched prefix
        if set(s).issubset(set(map(str, digits))):
            if res is None or s < res:
                res = s

    # try longer length
    if digits[0] != 0:
        cand = str(digits[0]) * (n + 1)
        if res is None or cand < res:
            res = cand

    return res

def solve():
    t = int(input())
    for _ in range(t):
        n, k = input().split()
        n = n.strip()

        best = None

        # generate digit sets
        for a in range(10):
            for b in range(a, 10):
                digits = {a}
                if k == 2:
                    digits.add(b)

                if len(digits) > k:
                    continue

                cand = build_with_set(n, digits)
                if cand is None:
                    continue
                if best is None or int(cand) < int(best):
                    best = cand

        print(best)

if __name__ == "__main__":
    solve()
```该解决方案最多枚举所有有效的大小的数字集`k`。 对于每个集合，它构造不小于的最小数`n`通过尝试匹配`n`贪婪地从左到右，并在第一个位置处中断，在该位置我们可以在保持在允许的集合内的同时增加一位数字。 

微妙的一点是正确处理前缀相等。 如果我们设法遵循`n`完全地，我们仍然必须确保所使用的数字是有效的； 否则我们会拒绝该候选人。 回退到更长的数字可以确保我们不会错过类似的情况`999`带数字集`{1}`答案必须变成`1111`。

 ### 示例 1

 输入：`n = 177890, k = 2`我们考虑数字集，例如`{1,7}`,`{1,8}`,`{1,9}`等。最优集结果是`{1,8}`。 

| 步骤| 前缀匹配 | 行动| 候选人|
 | --- | --- | --- | --- |
 | 1 | “” | 开始 | - |
 | 2 | “1”| 比赛 1 | - |
 | 3 | “17”| 比赛 7 | - |

 | 5 | “1778”| 将 7 替换为 8 | 181111 |

 当我们增加一个数字来逃避约束，然后用集合中最小的数字填充时，就会发生第一个偏差。 

最终答案：`181111`。 

### 示例 2

 输入：`n = 998244353, k = 1`仅允许大小为 1 的数字集。 我们测试`{0}`,`{1}`, ...,`{9}`。 

| 数字集| 构造数|
 | --- | --- |
 | {0} | 无效前导|
 | {1} | 111111111 |
 | {9} | 999999999 |

 最小有效数≥`n`是`999999999`。 

这证实了对于`k = 1`，问题就简化为选择一个可以重复的数字。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def build_with_set(s, digits):
        digits = sorted(digits)
        n = len(s)
        res = None

        for i in range(n):
            ok = False
            for d in digits:
                if i == 0 and d == 0:
                    continue
                if d > s[i]:
                    cand = s[:i] + str(d) + digits[0]*(n-i-1)
                    res = cand if res is None else min(res, cand)
                    ok = True
                    break
                elif d == s[i]:
                    ok = True
                    break
            if not ok:
                break
        else:
            if all(c in set(map(str, digits)) for c in s):
                res = s if res is None else min(res, s)

        if digits[0] != 0:
            cand = str(digits[0]) * (len(s)+1)
            res = cand if res is None else min(res, cand)

        return res

    def solve():
        t = int(input())
        for _ in range(t):
            n, k = input().split()
            best = None
            for a in range(10):

 ## 边缘情况

 出现关键边缘情况时`n`已经只使用了一位数字，但是`k = 2`。 例如，`n = 111`和`k = 2`应该保留`111`。 该算法处理这个问题是因为数字集`{1}`当无法改进时，始终会考虑并重建相同的数字。 

另一个边缘情况是，提前增加一个数字会产生一个较小的后缀来补偿增加的情况。 例如，当`n = 177890`，切换自`7`到`8`在某个位置允许后缀变成全部`1`s，产生一个比任何试图保持接近的全局更小的有效数字`n`。 

最后，像这样的案例`999`和`k = 1`确保算法正确地转换为更长的长度数字。 重复最小数字的结构保证我们不会错过最小有效扩展。
