 ## 解决方案
 ## 问题理解

 我们被要求生成波利卡普“喜欢”的正整数序列。 如果一个数字不能被 3 整除并且不以数字 3 结尾，则该数字为“喜欢”。给定一个整数$k$，任务是输出$k$此序列中的第 - 个数字。 提供了多个测试用例，每个测试用例都有一个单独的$k$。 

输入包括$t$，测试用例的数量，然后是$t$整数$k$。 每个$k$最多可以有 1000 个，并且最多可以有 100 个测试用例。 由于我们可能需要的最大数量不大（几千），因此我们可以使用简单的方法，例如顺序迭代整数。 这些约束排除了需要搜索数百万个数字的解决方案，但允许线性方法过滤数字，直到达到$k$第 - 个有效的。 

由于必须跳过可被 3 整除或以 3 结尾的数字，因此会出现不明显的边缘情况。 例如，假设每三个数字都是坏数字的天真方法就会失败：像 13、23、16 这样的数字会以不同的方式被跳过，因为除了整除性之外，结尾数字也很重要。 一个小例子说明了这一点：第 9 个喜欢的号码是 14，而不是 13 或 15。粗心的索引很容易在这里计数错误。 

## 方法

 蛮力方法很简单。 从 1 开始，遍历整数，跳过那些能被 3 整除或以 3 结尾的整数。计算我们看到了多少个喜欢的数字，当达到$k$-th。 这保证可以工作，因为我们检查每个数字，但如果$k$非常大，因为它可能需要迭代超过$k$数字。 

一个关键的观察简化了这一点。 任何以 3 结尾或能被 3 整除的数字都必须被跳过。 没有直接的公式可以跳转到$k$-th 个数字，因为跳过是不规则的：每第十个以 3 结尾的数字都是坏数字，每三个能被 3 整除的数字都是坏数字，有时这些数字会重叠。 然而，对于$k \le 1000$，简单地按顺序生成数字就足够快了，超出此范围的优化是不必要的。 如果$k$如果要大得多，可以使用预先计算的列表或基于对跳过的数字进行计数的数学模式，但这种公式的复杂性比仅仅迭代要高。 

对比表：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 每个测试用例的 O(k) | O(1) | O(1) | 已接受 |
 | 预计算列表 | O(max_k) | O(max_k) | 已接受但没有必要 |

 ## 算法演练

 1. 初始化一个计数器，记录我们看到的喜欢号码的数量。 从零开始。 
2. 将当前数字初始化为1。 
3. 当计数器小于$k$，查看当前号码。 
4. 如果数字能被3整除或以3结尾，则跳过它。 否则，增加计数器。 
5. 增加当前数字并重复步骤 3。 
6. 一旦计数器达到$k$，最后考虑的数字是$k$第 - 个喜欢的号码。 返回它。 

不变的是，计数器准确地跟踪我们看到的喜欢的号码的数量。 我们只增加有效数字的计数器，因此当计数器等于$k$，我们保证已经达到$k$第 - 个喜欢的号码。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def kth_liked_number(k):
    count = 0
    num = 1
    while True:
        if num % 3 != 0 and num % 10 != 3:
            count += 1
            if count == k:
                return num
        num += 1

t = int(input())
for _ in range(t):
    k = int(input())
    print(kth_liked_number(k))
```功能`kth_liked_number`按顺序遍历整数，仅在喜欢某个数字时才增加计数器。 主循环处理多个测试用例。 注意病情`num % 10 != 3`而不是检查字符串表示，这稍微快一些。 使用`while True`允许我们尽快退出$k$找到第 - 个数字。

 ## 边缘情况

 对于 k = 1，第一个喜欢的数字是 1。算法从 1 开始计数，并且仅当数字被喜欢时才正确地递增计数器。 第一个数字之前不会出现跳过的数字。 对于 k = 1000，算法持续到 1666，正确地跳过所有 3 的倍数和以 3 结尾的数字。数字周围的边缘情况（如 3、6、13、33）由条件处理`num % 3 != 0 and num % 10 != 3`，这确保计数器仅针对有效数字而增加。
