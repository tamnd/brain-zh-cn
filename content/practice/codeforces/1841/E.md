 ## 解决方案
 ## 问题理解

 矩阵的每一列都包含一个黑色前缀和一个白色后缀。 栏内`i`, 行`1..a_i`被阻塞，而行`a_i+1..n`可用。 

我们必须将整数`1,2,...,m`成不同的白细胞。 美女数数连续有多少对`(j, j+1)`最终出现在同一行的水平相邻单元格中，其中`j+1`立即在右侧`j`。 

数字的实际值仅通过它们的顺序起作用。 每当我们将连续的数字放在白色单元格的水平段内时，该段包含`k`数字准确贡献`k-1`美丽，因为该运行中的每一对相邻的对都贡献一次。 

矩阵大小最多为`2·10^5`跨所有测试用例。 任何明确触及所有内容的算法`n²`细胞是不可能的。 即使存储整个矩阵也太昂贵了。 白细胞的结构必须直接从阵列中利用`a`。 

一个微妙的点是`m`可以非常大。 该语句明确警告它可能不适合 32 位整数。 每个涉及放置值数量的计算都必须使用 64 位算术。 

另一个容易犯的错误是认为每一行都可以独立处理。 考虑：```
n = 3
a = [0,0,0]
m = 9
```所有细胞都是白色的。 长度为三行段`3`。 充分填充每一个都赋予美丽`2 + 2 + 2 = 6`，这是最优的。 在这里独立处理行就可以了。 

现在考虑：```
n = 4
a = [2,0,3,1]
m = 5
```行段具有不同的长度。 在短片段上花费大量资金可能会降低最终的美感，因为每个新片段都会受到一分的惩罚。 最佳策略由段长度驱动，而不是由行本身驱动。 

当剩余的整数不能完全填满下一个段时，就会出现第三个陷阱。 对于一段长度`L`，仅放置`x < L`数字贡献`x-1`， 不是`x`。 缺少此细节会在最后的贪婪步骤中产生差一错误。 

## 方法

 首先，暴力视图是有用的。 

想象一下提取每个最大水平白色段。 如果一个线段有长度`L`，然后填充`k`该部位的细胞连续产生美丽`k-1`每当`k > 0`。 

假设我们知道所有细分。 然后我们可以尝试每一种可能的分布`m`其中的数字。 这显然是正确的，因为美丽仅取决于每个段接收到的数字数量。 不幸的是，分布的数量是巨大的，甚至天真地生成所有段也需要检查整个矩阵，其中可能包含大约`4·10^10`细胞。 

关键的观察是填充段`k`数字贡献```
k - 1
```可以重写为```
k - (number of used segments)
```对所有部分进行求和。 

由于所下号码的总数是固定的并且等于`m`，最大化美度相当于最小化接收至少一个数字的段数。 

这立即表明了一种贪婪的策略。 如果我们有多个可用段，我们应该首先填充最长的段。 长段可以吸收许多数字，同时支付与短段相同的“一个段”惩罚。 

现在问题就变成了：

 1. 找出每个可能的长度存在多少个最大水平白色线段。 
2. 花费`m`线段上从最大长度到最小长度的编号。 

剩下的挑战是在不构建矩阵的情况下提取所有最大水平白色段。 

对于一行`r`， 柱子`i`是白色的`a_i < r`。 最大水平段对应于所有高度都低于某个行水平的列间隔。 

这与直方图问题中出现的结构完全相同。 使用单调堆栈，我们可以计算每个长度存在多少个最大段。 堆栈处理由以下方式形成的天际线`a_i`，并且每次弹出都确定范围长度以及生成该范围的行级别数。 

获得后`cnt[len]`，最大长度段的数量`len`，贪婪填充很简单。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) 或更糟 | O(n²) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 除了迭代长度之外，下面的实现实际上以线性时间运行。 

## 算法演练

 1. 解释`a_i`作为阻塞单元格的列高。 
2.添加两个高度的哨兵列`n`在两端。 这些保证了每个段最终都会被关闭和计数。 
3. 使用递减单调堆栈处理数组。 
4. 每当当前高度至少等于前一列的高度时，就开始弹出堆栈元素。 
5. 在弹出过程中，每个弹出高度代表一系列行级别，这些行级别创建特定长度的最大水平白色段。 将这些贡献累积到`cnt[length]`。 
6. 在允许弹出所有内容后，如果堆栈仍然非空，则将上次弹出高度和当前高度之间生成的剩余贡献相加。 
7. 处理完每一列后，`cnt[len]`存储有多少最大白色段的长度`len`。 
8. 从最大到最小的行程长度。 
9.对于长度`L`有计数`C`：

- 如果`m >= L·C`，完全填充所有这些段。 
- 每个完全填充的部分都有贡献`L-1`。 
- 减法`L·C`从`m`。 
10. 如果没有足够的数字来填充所有`C`细分：

 - 完全填满`m // L`段。 
- 使用剩余部分`m % L`在一个附加段内。 
- 部分填充的段`r`数字贡献`r-1`什么时候`r > 0`。 
- 在此步骤之后，所有数字都被使用并且算法停止。 

### 为什么它有效

 与放置在其中的整数数量相比，每个被占用的段恰好支付一个单位的美观损失。 

对于接收段`k`数字：```
beauty = k - 1
```对所有使用的段求和得出```
beauty = m - used_segments
```因为放置的整数总数固定为`m`。 

为了最大化美观，我们必须最小化接收数字的段数。 实现此目的的最佳方法始终是首先消耗最长可用段的容量。 任何在存在较长未使用段的情况下使用较短段的解决方案都可以通过将数字从较短段移动到较长段而得到改进，而不增加占用段的数量。 

单调堆栈正确地计算了最大白色段，因为每次弹出都准确地标识了某个高度为限制边界的区间。 相邻高度之间的差异决定了有多少行级别生成该间隔长度。 这是标准的直方图分解论证。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        m = int(input())

        a = [n] + arr + [n]
        N = n + 1

        stack = [0]
        cnt = {}

        for i in range(1, N + 1):
            if a[i] >= a[i - 1]:
                prev = a[stack[-1]]
                stack.pop()

                while stack and a[stack[-1]] <= a[i]:
                    length = i - stack[-1] - 1
                    cnt[length] = cnt.get(length, 0) + (a[stack[-1]] - prev)
                    prev = a[stack[-1]]
                    stack.pop()

                if stack:
                    length = i - stack[-1] - 1
                    cnt[length] = cnt.get(length, 0) + (a[i] - prev)

            stack.append(i)

        ans = 0

        for length in sorted(cnt.keys(), reverse=True):
            if length == 1:
                continue

            c = cnt[length]
            total_cells = length * c

            if total_cells <= m:
                ans += c * (length - 1)
                m -= total_cells
            else:
                full = m // length
                ans += full * (length - 1)
                m -= full * length

                if m > 0:
                    ans += m - 1

                m = 0
                break

            if m == 0:
                break

        print(ans)

solve()
```代码的第一部分对由列高形成的直方图执行单调堆栈分解。 字典`cnt`存储每个长度存在的最大水平段数。 

变量`prev`是关键的细节。 连续的弹出高度代表行级别的不同带。 使用高度差可以避免多次计算同一行级别。 

在知道所有段计数后，贪婪阶段从最大长度向下迭代。 完全填充的长度段`L`贡献`L-1`，这就是更新的原因：```
ans += count * (L - 1)
```部分填充的情况是最容易出错的地方。 如果余数是`r`，贡献是`r-1`， 不是`r`。 什么时候`r = 0`，不存在额外的段，因此没有添加任何内容。 

Python 整数自动处理较大的值`m`。

 ## 边缘情况

 考虑：```
1
1
0
1
```恰好有一个白细胞。 唯一可能的放置方式是使用包含一个数字的一​​个段。 美是`1 - 1 = 0`。 贪婪阶段永远不会从长度为 1 的段中获得任何东西，因此算法正确地输出`0`。 

考虑：```
1
2
0 0
3
```有两行长度的段`2`。 该算法首先完全填充一个段，获得`1`美丽并使用两个数字。 留下一个号码并开始另一段，贡献`0`。 总的美丽是`2 - 1 = 1`从第一段加上`0`从第二个开始，给予`2`全面的。 部分填充规则`r - 1`准确地处理这个问题。 

考虑：```
1
3
3 3 3
0
```每个细胞都是黑色的。 堆栈分解不会产生有用的段长度。 贪婪阶段不执行任何操作并返回`0`，这是唯一可能的答案。 

最后，考虑剩余数字停在长段中间的情况：```
1
3
0 0 0
4
```最好的策略是将所有四个数字放在长度为 3 的段内，然后仅在必要时继续进入另一个段。 该算法完全填充了一个长度为3的段，增益`2`，剩下的单个数贡献`0`。 答案是`2`，匹配最优结构。
