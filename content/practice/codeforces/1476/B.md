 ## 解决方案
 ## 问题理解

 我们得到了单一产品每月价格上涨的序列。 第一个值代表初始价格，随后的每个值都是该月的名义涨幅。 我们被要求确保每月通货膨胀百分比（按当月涨幅与截至该月的累计价格之比计算）不超过给定阈值$k$百分比。 为了实现这一目标，我们可以提高初始价格和/或前几个月的价格，但我们希望这样做的同时最大限度地减少添加的总额外金额。 

每个测试用例提供月数$n$, 最大允许通货膨胀百分比$k$，以及价格上涨的数组$p$。 每个测试用例的输出是一个整数，即需要添加到数组中以使通货膨胀约束适用于每个月的最小总和。 

限制条件适中：$n$最多 100 并且$t$最多 1000，这意味着该解决方案应该在$O(n)$每个测试用例。 个别价格上涨幅度可达$10^9$，这排除了依赖于所有可能的价格增加的简单暴力枚举的方法。 当非常小的初始价格随后大幅上涨时，就会出现不明显的边缘情况：如果不进行调整，通货膨胀系数将超过$k$大幅领先。 例如，与$p = [1, 100]$和$k = 1$第二个月的涨幅是初始价格的100倍，远高于1%的上限。 一个简单的解决方案，仅检查是否$p_i \le k$彻底失败。 

## 方法

 暴力方法将考虑每个月累积总和的所有可能增量，并检查哪种组合满足通货膨胀上限。 这种方法是正确的，但不切实际：对于每个月，都有可能$O(10^9)$需要考虑的增量，导致操作计数达到天文数字。 

关键的见解是问题可以从左到右贪婪地解决。 当月通货膨胀系数$i$定义为$p_i / S$， 在哪里$S$是调整后所有先前值的总和。 为确保$p_i / S \le k / 100$，我们可以求解所需的最小累积和$S$作为$S \ge \lceil (p_i \cdot 100) / k \rceil$。 如果当前累计总和小于此值，我们将差值添加到运行总计中。 通过按顺序处理月份，我们总是最小限度地调整总增量以满足约束，确保我们不会过度补偿。 这是线性的$n$并在给定的范围内工作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O((最大 p_i)^n) | O(n) | 太慢了 |
 | 贪婪顺序 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化`total_add`为零以跟踪所有添加的总和并设置`cumulative`至第一个月的价格。 
2. 从第二个月到最后一个月迭代几个月。 
3. 每个月$i$，计算所需的最小累积和为`(p[i] * 100 + k - 1) // k`。 这个公式确保我们四舍五入到最接近的整数。 
4. 如果当前累计金额`cumulative`小于所需的最小值，计算差值并将其添加到`total_add`。 更新`cumulative`通过添加这个差异。 
5.添加当月价格`p[i]`到`cumulative`，反映出我们现在将本月纳入后续几个月的总数中。 
6.处理完所有月份后，输出`total_add`。 

不变的是处理月份后$i$，累计总和总是足以使所有月份的通货膨胀保持在$i$以下$k$百分比。 通过维持这个不变量，我们确保通货膨胀约束永远不会被违反。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        p = list(map(int, input().split()))
        total_add = 0
        cumulative = p[0]
        for i in range(1, n):
            required = (p[i] * 100 + k - 1) // k
            if cumulative < required:
                add = required - cumulative
                total_add += add
                cumulative += add
            cumulative += p[i]
        print(total_add)

if __name__ == "__main__":
    solve()
```该代码首先读取测试用例的数量并单独处理每个测试用例。 我们初始化`total_add`归零并设置`cumulative`为第一个月的价格，反映起始价格。 该循环使用上限除法计算所需的累积和以处理整数舍入。 如果当前累计金额不足，我们添加必要的金额`total_add`并更新`cumulative`。 最后，我们将当月的价格添加到`cumulative`以供将来检查。 始终使用整数运算可以避免浮点错误。

 ## 边缘情况

 对于输入`2 1\n1 100`，累计从 1 开始。第 1 个月需要`100 * 100 / 1 = 10000`，所以我们添加`10000 - 1 = 9999`为累加，加起来的总数为9999。算法正确地应用了上限除法并按顺序更新累加。 为了`4 10\n10 1 1 100`，该算法在上个月之前添加 90 以满足 10% 的上限，这表明后续几个月的连续更新可以正确累积。
