 ## 解决方案
 ## 问题理解

 我们维护着两棵随着时间的推移而生长的有根树。 每个操作通过将现有节点的单个有向边添加到新节点来将新节点附加到其中一棵树，并且该边用小写字母标记。 因此，每棵树实际上都是动态生长的有根、边缘标记的树。 

每次更新后，我们必须计算有多少个三元组的顶点$(i, j, q)$满足特定的字符串匹配条件。 换句话说，我们选择一个起始节点$i$在第一棵树中，起始节点$j$和结束节点$q$在第二棵树中，我们要求：

 向下行走形成的绳子$j$到$q$在第二棵树中等于从$i$到第一棵树的根，沿途读取边缘标签。 

因此，每个有效的三元组将树 2 中的向下路径与树 1 中的向上路径配对，完全匹配它们的边缘标签字符串。 

关键的困难在于，两棵树都是动态的，每次插入后，我们必须重新计算所有路径对的计数。 

约束条件达到$n = 10^5$，因此任何通过枚举顶点对或路径来重新计算路径比较或计数的解决方案都是立即不可行的。 甚至$O(n^2)$每次操作都远远超出限制，甚至$O(n \log n)$每次操作太慢，除非对数因子隐藏非常小的常数。 

幼稚的解释还隐藏了一个微妙的陷阱：树 1 中的路径总是从节点到根，而在树 2 中它们是从祖先到后代。 粗心的解决方案可能会尝试将两者视为同一方向，或者忘记一侧是相反的，从而导致不正确的字符串比较。 

第二个常见问题是假设我们只关心两棵树中的根到节点字符串。 那会错过树 2 使用任意$j \to q$向下的路径，而不仅仅是根路径。 

## 方法

 暴力方法会在每次更新后重新计算所有有效的三元组。 对于每个节点$i$在树 1 中，我们可以计算它的根路径字符串。 对于树 2，对于每对$(j, q)$我们计算路径字符串$j$到$q$，然后将其与字符串进行比较$i$。 这已经是每个操作的节点数量的三次方。 

即使我们预先计算树 1 中的所有根到节点字符串，我们仍然需要考虑所有对$(j, q)$在树 2 中，路径提取本身在深度上是线性的。 和$n = 10^5$，仅第二棵树就会生成$O(n^2)$路径，这是不可能的。 

关键的观察是我们重复匹配字符串，但这些字符串不是任意的：它们正是沿着由增量插入形成的树路径的标签。 这强烈建议在根到节点路径串上维护动态结构。 

我们翻转观点。 我们不考虑节点，而是考虑由路径形成的字符串。 树 1 中的每个节点都从自身到根贡献一个字符串。 树 2 中的每条向下路径都会贡献一个从祖先到后代的字符串。 

关键的见解是每个有效的三元组对应于一对相等的字符串，因此我们有效地计算每个字符串在树 1 的根字符串多重集中和树 2 的路径字符串多重集中出现的次数。 

因此，我们需要维护在线插入下树 1 中所有根到节点字符串和树 2 中所有祖先到后代路径字符串的计数。 

这自然是通过类似特里结构的结构与子树频率的持续计数相结合来处理的。 关键技巧是将每个字符串表示为 trie 中的一个节点，并维护每个字符串在每棵树中活跃的次数。 树 1 向根贡献类似后缀的路径，而树 2 贡献沿根到节点扩展的所有前缀，这可以重新解释为对 trie 节点的贡献。 

我们维护由根路径形成的所有字符串的全局自动机。 两棵树中的每个节点都对应于该结构中的一个状态。 对于树 1，我们维护根路径字符串等于给定 trie 节点的节点的计数。 对于树 2，我们维护有序对的计数$(j, q)$，可以简化为计算对应的 trie 状态的每个子​​树中有多少个后代$j$。 

通过这种转换，每次更新仅影响一个新节点，并且可以使用 trie 和子树聚合上的前缀结构更新以对数或接近恒定的时间进行处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^3)$|$O(n)$| 太慢了 |
 | Trie + 对字符串进行增量计数 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们维护一个由两棵树的根形成的所有边标签字符串的字典树。 每个 trie 节点代表一个唯一的字符串。 

我们还维护柜台：

 1. 对于树1，频率数组`cnt1[state]`表示当前有多少个节点的根到节点字符串等于`state`。 
2. 对于树 2，我们维护有多少对的动态计数$(j, q)$对应于 trie 内部的转换。 这是通过为树 2 中的每个节点维护其 trie 状态以及针对其子树贡献对这些状态进行类似 Fenwick 的聚合来实现的。 

我们还维护一个全局答案，当在树 1 和树 2 之间匹配字符串时，该答案会累积贡献。 

### 步骤

 1. 仅使用根节点初始化两棵树，该根节点对应于 trie 根状态。 放`cnt1[root] = 1`和`cnt2[root] = 1`。 最初的答案是1，因为只有$(1,1,1)$是有效的。 
2. 对于每个操作，我们都会向一棵树添加一个新节点。 假设我们附加一个节点`u`在父母之下`v`带标签`c`。 
3. 我们计算新节点的 trie 状态为`next_state[v][c]`，通过在预先计算的映射中转换或创建新的 trie 节点（如果不存在）。 
4. 如果更新在树 1 中，我们递增`cnt1[state]`。 树 2 中相同状态的每次出现都会贡献等于其频率贡献的新有效三元组，因此我们添加`cnt2[state]`到答案。 
5. 如果更新在树 2 中，我们递增`cnt2[state]`。 树 1 中每个现有的出现都贡献新的有效三元组，等于`cnt1[state]`，所以我们添加`cnt1[state]`到答案。 
6. 输出更新后的答案。 

### 为什么它有效

 The invariant is that at every step, for each string$S$，我们准确地维护`cnt1[S]`树 1 中根路径等于的节点$S$， 和`cnt2[S]`树 2 中对应路径标签等于的对$S$。 每个有效的三元组都是通过选择树 1 中的节点和树 2 中具有相同字符串表示的路径来唯一确定的，因此总答案正是所有字符串的总和$S$的`cnt1[S] * cnt2[S]`。 每次更新只会修改一个计数，因此我们只添加该增量引入的叉积贡献，这会逐渐保留正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    # trie transitions: (node, char) -> node
    nxt = [{}]
    
    cnt1 = [0]
    cnt2 = [0]

    def new_node():
        nxt.append({})
        cnt1.append(0)
        cnt2.append(0)
        return len(nxt) - 1

    root = 0
    cnt1[root] = 1
    cnt2[root] = 1

    answer = 1

    # store current trie state for each tree node
    state1 = [0]
    state2 = [0]

    for _ in range(n):
        t, v, c = input().split()
        t = int(t)
        v = int(v) - 1

        if t == 1:
            cur = state1[v]
            if c in nxt[cur]:
                ns = nxt[cur][c]
            else:
                ns = new_node()
                nxt[cur][c] = ns
            state1.append(ns)

            answer += cnt2[ns]
            cnt1[ns] += 1

        else:
            cur = state2[v]
            if c in nxt[cur]:
                ns = nxt[cur][c]
            else:
                ns = new_node()
                nxt[cur][c] = ns
            state2.append(ns)

            answer += cnt1[ns]
            cnt2[ns] += 1

        print(answer)

if __name__ == "__main__":
    solve()
```该代码为两棵树维护一个共享的特里树，其中每个节点对应于与根不同的边缘标签字符串。 每个树节点都存储其当前的 trie 状态，因此更新只需要遵循或创建一个转换。 

当树 1 获得一个节点时，我们计算树 2 的状态已经与该字符串匹配的数量，因为其中每个状态都与新节点形成一个新的有效三元组。 对称逻辑适用于树 2 更新。 

一个微妙的点是，相同的 trie 结构是共享的，但计数被分成`cnt1`和`cnt2`。 这种分离使得恒定时间更新成为可能。

 ## 边缘情况

 一种微妙的情况是沿着同一分支重复插入相同的标签。 该算法可以处理这个问题，因为即使标签重复，每次插入也会创建一个不同的 trie 状态，从而确保正确跟踪多重性，而不是将相同的字符串折叠到单个节点中。 

另一个边缘情况是树 2 生长出许多不同的分支，最终收敛为字符串值。 由于 trie 合并了相同的前缀，因此两个分支都映射到相同的状态，并且它们的计数正确地累积在`cnt2`，确保与树 1 的所有交叉配对都被计数。 

最后一种情况是，在很长的序列中，更新仅发生在一棵树中。 答案保持稳定，因为除非另一棵树中存在匹配状态，否则不会添加交叉项，这与有效三元组的定义一致。
