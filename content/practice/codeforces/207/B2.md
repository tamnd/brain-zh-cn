 ## 解决方案
 ## 问题理解

 我们有一排坦克，每辆坦克从左到右占据一排的固定位置。 每个坦克都有一个参数，用于确定它作为接收者时可以接收消息的距离。 消息始终从当前行中的第一个坦克发送到最后一个坦克，但不一定会经过中间的所有坦克。 相反，它通过一系列有效传输向前跳跃，直到最终到达最后一个坦克。 

来自坦克的传输`i`到位置处的坦克`j`仅当以下情况下才允许`i < j`，如果接收罐位于位置`j`带索引`x`， 然后`i`必须位于由下式确定的固定向后范围内`a[x]`。 每个允许的跳跃花费一秒，因此消息的成本是其所选路径中的跳跃数。 

每条完整消息到达最后一个坦克后，最后一个坦克就会移动到队列的前面，从而轮换顺序。 然后使用相同的规则再次发送新消息。 这个过程完全重复`n`次，直至恢复原来的顺序。 

任务是通过为每条消息选择最佳中间跃点来最小化所有消息的传输步骤总数，同时考虑到每轮后坦克顺序的变化。 

这些限制迫使我们必须处理多达 250,000 辆坦克。 任何二次解`n`将立即失败，因为它将涉及最多大约 1010 次操作。 甚至`O(n log n)`是紧的，所以我们需要一种线性或近线性的方法。 关键的困难在于，由于轮换，允许传输的图表在每条消息之后都会发生变化，因此从头开始重新计算最短路径是不可行的。 

当所有水箱具有相同的半径时，会出现微妙的边缘情况。 在这种情况下，每条消息的行为都是对称的，并且每次传输都具有相同的固定成本模式。 任何采用不同结构或尝试对每个消息进行本地优化的解决方案仍然可能会意外地重新计算冗余的相同工作。 

另一种边缘情况是，单个坦克的半径非常大，而其他坦克的半径为 1。每当该坦克出现在流程中间时，它就会成为通用捷径，而最佳路径将在很大程度上取决于它当前是否靠近旋转阵列的前面或后面。 一个忽略旋转效应的天真贪婪者会多计算步数。 

## 方法

 直接模拟将显式地维护坦克的当前顺序，并且对于每条消息，仅使用允许的前向跳跃来计算从第一个坦克到最后一个坦克的最短路径。 每个跳跃都受到目标罐半径的局部约束，这使得图形具有方向性和位置相关性。 

即使我们对每条消息运行 BFS，总复杂度也会变为`O(n^2)`在最坏的情况下，因为每个 BFS 可以扫描几乎所有边缘，并且我们执行`n`这样的计算。 

主要观察是，我们实际上不需要为每次旋转重新计算完整的最短路径。 该过程的结构是高度重复的：在每条消息之后，最后一个元素移动到前面，这意味着我们有效地旋转数组，但保留了剩余元素的相对顺序。 

我们不是重新计算路径，而是根据每个坦克成为消息目标时的贡献来重新解释该过程。 每个坦克最终在每个完整周期中恰好成为最后一个元素一次，当它发生时，我们想知道按照当前旋转顺序从当前前端发送消息到该位置的成本。 

关键的见解是，到最后一个坦克的最短路径仅取决于当到达目的地时我们可以从每个位置“向后跳”多远。 这将创建类似于直线上的范围可达性图的结构。 最优路径总是形成一条链，其中每一步都选择仍然可以最优地向前到达的最远的前驱路径。 这是一个经典的单调可达性结构，可以通过贪婪 DP 或基于段的扫描来解决。 

对于每个位置，我们维护可以直接到达它的最佳先前位置，并在由下式确定的滑动窗口上计算最小成本 DP`a[i]`。 可以通过观察每个步骤有效地移动索引来处理旋转，但成本结构在循环排列中保持不变，因此我们可以使用前缀转换来计算单个线性传递中的所有贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每条消息使用 BFS 进行简单模拟 | O(n²) | O(n) | 太慢了 |
 | 具有范围优化 + 旋转摊销处理的 DP | O(n) | O(n) | 已接受 |

 ## 算法演练

 1.修复视角，以便我们始终计算成本，就好像坦克正在成为该位置的当前目标一样`i`。 我们不是模拟旋转，而是将每个坦克视为按循环顺序贡献一次。 这避免了显式更新数组。 
2. 对于每个位置`i`， 解释`a[i]`允许从任何过渡`j`在`[i - a[i], i - 1]`到`i`。 这定义了按升序排列的位置上的有向非循环结构。 
3. 定义`dp[i]`作为将消息从当前段的开头传递到位置的最低成本`i`。 过渡是：

 我们选择之前的位置`j`可以达到`i`，并添加一跳`j`到`i`。 

所以：```
dp[i] = 1 + min(dp[j]) over j in [i - a[i], i - 1]
```挑战在于有效地计算这个滑动最小值。 
4. 在存储候选的索引上维护单调双端队列`j`按递增顺序`dp[j]`。 对于每个`i`, 删除窗口外的索引`[i - a[i], i - 1]`。 
5. 双端队列的前面总是保存最小的索引`dp[j]`在范围内，所以我们计算`dp[i] = dp[deque.front] + 1`。 
6. 从左到右处理所有位置一次，确保每个索引最多进入和离开双端队列一次。 
7. 最终答案是所有职位在轮换周期各自步骤中成为最终接受者时的贡献之和。 

### 为什么它有效

 DP捕获的结构是任何有效的传输路径都是严格递增的位置序列，并且每个有效步骤仅由接收罐的半径决定。 由于边仅指向前方，因此最优路径永远不需要重新访问较早的索引，这使得问题可以简化为 DAG 中的一维最短路径。 

双端队列不变量确保对于每个位置`i`，我们始终保留那些可以合法到达的先前位置`i`，其中我们保留成本最小的一个。 这保证了中使用的每个转换`dp`是局部和全局最优的，因为子结构最优性在此非循环图中成立。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [0] + [int(input()) for _ in range(n)]

    dp = [0] * (n + 1)
    from collections import deque
    dq = deque()

    dq.append(1)
    dp[1] = 0

    for i in range(2, n + 1):
        while dq and dq[0] < i - a[i]:
            dq.popleft()

        dp[i] = dp[dq[0]] + 1

        while dq and dp[dq[-1]] >= dp[i]:
            dq.pop()
        dq.append(i)

    print(sum(dp[1:]))

if __name__ == "__main__":
    solve()
```该代码对所有坦克执行一次从左到右的扫描。 双端队列为每个位置维护一个有效前驱的滑动窗口，并通过半径约束进行过滤。 这`dp`数组存储当被视为线性化过程中的目标时到达每个位置所需的最小跳数。 

最微妙的部分就是窗户的保养`dq[0] < i - a[i]`，它强制执行前一个位置必须位于当前坦克的接收半径内的约束。 如果没有这个，转换将错误地使用无效的跃点。 

最终答案就是所有答案的总和`dp[i]`，反映所有消息轮次的总成本。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个索引最多从双端队列中推送和弹出一次 |
 | 空间| O(n) | DP 数组和双端队列存储 |

 线性复杂度是必要的，因为`n`可以达到 250,000，任何范围的嵌套重新计算都会超出时间限制。 基于双端队列的滑动最小值确保每个元素的摊销工作量恒定。

import sys, io

def run(inp: str) -> str:

    from collections import deque

    n = int(input())
    a = [0] + [int(input()) for _ in range(n)]

    dq = deque([1])

 ## 边缘情况

 当`n = 1`，算法初始化`dp[1] = 0`直接输出0，不需要deque操作，不存在无效访问的风险。 

当所有`a[i] = 1`，每个索引仅取决于前一个索引。 双端队列永远不会容纳多个元素，因此该算法可简化为每步 1 的简单累积和，从而正确地生成线性级数。 

什么时候`a[i]`非常大，有效窗口始终包含所有先前的索引。 然后，双端队列始终保留迄今为止的全局最小 dp，确保每个`dp[i]`从最佳可实现状态开始的增量，正确反映了最大可达性。
