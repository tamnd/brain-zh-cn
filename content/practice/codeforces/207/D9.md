 ## 解决方案
 ## 问题理解

 我们得到一个由三部分组成的单个文档：与分类无关的标识符号、标题行，然后是文档的全文内容。 每个文档都属于标记为 1、2 和 3 的三个固定主题之一。训练数据在概念上存在，但不要求我们直接在输入中使用它。 相反，任务是推断新的未见过的文档的主题。 

我们在运行时实际收到的是一个文档，我们必须输出它属于三个主题类中的哪一个。 唯一可用的信号是文本本身，包括标题和正文。 

每个文档的输入大小限制很小，最多大约 10 KB。 这就排除了比赛运行时内的大量学习或优化。 任何扫描文档固定次数或对所有字符执行简单字符串处理的解决方案都可以轻松满足限制。 任何涉及对数据集进行大规模成对比较或昂贵的相似性计算的事情都是不必要的，而且如果重复进行的话，速度会太慢。 

一个关键的微妙之处是除了原始文本之外没有结构化格式。 这意味着解决方案必须依赖于提取强大的词汇信号，例如单词、词频或区分标记。 标识符行必须完全忽略，并且在实践中标题通常比正文提供更多信息，因此不应将其视为元数据，而应将其视为同一文本流的一部分。 

一个幼稚的错误是尝试匹配整个文档或依赖于训练示例的精确子字符串匹配。 例如，如果一份培训文档包含有关贸易市场的句子，而测试文档对其进行了轻微的释义，则即使主题明显相同，精确匹配也会失败。 另一个错误是忽略标题行，它可能包含消除主题歧义的强关键字。 

误导性方法的示例：

 输入：```
123
Global trade news
Markets rise due to exports
```如果天真的匹配器期望从训练数据中获得准确的短语，即使“贸易”、“市场”和“出口”等词强烈指示主题 3，它也可能会失败。 

正确输出：```
3
```## 方法

 强力解释是将输入文档与每个训练文档进行比较，并使用全文比较或标记重叠来计算相似性。 这在概念上是可行的，因为同一主题的文档共享词汇模式。 然而，这需要为每个查询文档扫描可能很大的训练语料库。 如果训练集有 N 个大小最大为 M 的文档，则每个查询的简单比较成本为 O(NM)，即使对于中等大小的 N，这也变得不切实际。 

关键的观察是我们实际上并不需要文档级匹配。 问题归结为单词级分类。 每个主题都可以用单词的分布来表示，分类就变成了一个评分问题：我们将文档分配给单词配置文件与文档单词最匹配的类。 

这使我们能够将所有训练信息压缩到每个类别的单个频率模型中。 在预处理过程中，我们计算每个单词在第 1、2 和 3 类文档中出现的频率。在预测时，我们对输入文档进行标记，并通过求和单词的频率（或对数频率）来计算每个类的分数。 

这将问题从文档比较转换为对输入文本的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 强力文档匹配 | O(N·M) | O(N·M) | 太慢了|
 | 词频分类| O(M)| O(V) | 已接受 |

 这里V是词汇量大小，M是输入文档的大小。 

## 算法演练

 我们假设训练阶段已经构建了三个字典，将单词映射到每个类别的频率。 

1.读取文档id并忽略它。 它不携带语义信息，并且不得影响评分。 
2. 读取标题行和其余行，将它们全部视为单个文本流。 原因是主题信号分布在标题和正文中。 
3. 使用空格分隔将文本拆分为标记，并可选择大小写标准化。 这确保了“贸易”和“贸易”得到相同的对待，避免了人为的计数稀疏。 
4. 初始化三个分数，每个科目一个，全部设置为零。 这些分数代表文档与每个主题的兼容性程度。 
5. 对于文档中的每个标记，通过添加该标记在相应类别模型中的频率（或加权频率）来更新每个类别分数。 类中不存在的令牌贡献为零。 
6. 处理完所有标记后，比较三个分数并输出最大的索引。 如果没有另外指定，平局可以任意解决，但在实践中，由于词汇差异，平局很少见。 

### 为什么它有效

 该算法依赖于每个类模型编码该主题中单词的经验分布的不变量。 每个标记与其所属类别的特征成正比。 对所有标记的贡献求和相当于在词袋假设下估计哪个类最有可能生成文档。 因为每个单词都是独立贡献的，所以线性累积保留了跨类的可能性的排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# In a real contest setting, this would be trained offline.
# Here we assume precomputed word frequency dictionaries exist:
# freq[cls][word] = count or weight
freq = {
    1: {},
    2: {},
    3: {}
}

def score(text, cls):
    s = 0
    f = freq[cls]
    for w in text:
        s += f.get(w, 0)
    return s

def main():
    doc_id = input().strip()
    title = input().strip()
    body = sys.stdin.read().strip().split()

    tokens = title.split() + body

    # simple normalization
    tokens = [t.lower() for t in tokens]

    scores = [
        score(tokens, 1),
        score(tokens, 2),
        score(tokens, 3),
    ]

    print(1 + max(range(3), key=lambda i: scores[i]))

if __name__ == "__main__":
    main()
```该实现将阅读与评分分开，以便标记化不会干扰分类逻辑。 小写确保与频率模型的一致匹配。 评分函数故意简单：它只累积字典查找的贡献，这使运行时与文档大小呈线性关系。 

一个微妙的点是将标题和正文合并到一个标记列表中。 如果无意中以不同的权重单独处理它们，则可能会出现分类偏差。 在这里他们受到统一的对待。

 ## 边缘情况

 一种边缘情况是文档主要包含停用词，几乎没有有意义的词汇。 

输入：```
1
a
the and in the and
```在这里，所有代币在所有类别中都映射到接近零的贡献。 该算法为所有类别产生相同的分数。 在这种情况下，由于索引排序，平局打破规则默认选择类别 1。 这是一致的，因为不存在区分类别的证据。 

另一个极端情况是极度倾斜的重复。 

输入：```
2
trade trade trade
trade trade trade trade trade
```重复的代币“交易”极大地提高了频率最高的类别的分数。 该算法正确地放大了强信号，因为累积的发生次数是线性的。 

最后一个边缘情况是混合主题词汇，其中两个类别具有相似的重叠。 评分差异变小，但由于每个单词独立贡献，即使轻微的频率不平衡也会在文档长度上累积，最终正确地分离类别。
