[CF 207A2 - 海狸计算器 1.0](https://codeforces.com/problemset/problem/207/A2)

 **标签：** 贪婪
 **求解时间：** 1m 11s

 ## 解决方案
 ## 问题理解

 我们得到了几个独立的整数序列，每个科学家一个序列。 每个序列必须保持其原始的内部顺序，但在形成一个全局列表时，我们可以任意交错这些序列。 

最终列表中的每个相邻对都根据序列值是否下降来判断是好还是坏。 当较大的数字紧随其后紧随较小的数字时，就会出现坏对。 目标是排列所有序列中的所有元素，尊重内部顺序约束，以便最终串联中不良相邻对的数量尽可能小。 

输入未明确列出所有数字。 相反，每个科学家的序列都是通过递归生成的，因此只给出第一个值，其余的可以计算。 总输出（所有数字都展开）可能很大，最多可达约 200,000 个元素，这迫使所有序列的总大小几乎呈线性解决方案。 

这立即排除了任何试图直接枚举序列的所有排列或交错元素的方法。 即使独立处理每个元素并进行全局排序也是不可能的，因为每个科学家序列中的元素都是按顺序锁定的。 

查看结构的一个有用方法是，每个科学家都贡献一条固定的路径，而我们将这些路径缝合在一起。 在每条路径内部，一些不良的相邻对是不可避免的，因为它们的顺序是固定的。 唯一的自由在于决定这些路径的连接顺序。 

当序列内部严格递减时，会出现微妙的边缘情况。 例如，如果一位科学家生产出`5, 4, 3`，那么每个内部转换都已经是坏对并且无法改进。 任何正确的解决方案都不得尝试通过混合其他序列中的元素来“修复”此类情况，因为内部顺序是严格执行的。 

当两个序列具有相同的边界值时，例如开始和结束的数字都相同，就会出现另一种极端情况。 在这种情况下，交换它们的顺序不会影响成本，并且天真的贪婪策略不能假设严格的排序。 

## 方法

 强力解决方案会将每个科学家的序列视为一个块，并尝试这些块的每种排列。 对于每个排列，我们将连接序列并计算所有坏的相邻对。 这是正确的，因为它尊重所有约束，但它立即不可行。 对于多达 5000 个序列，排列的数量是天文数字，甚至评估一种排列所花费的时间与元素总数呈线性关系。 

关键的观察是每个序列内部的排序永远不会改变，因此无论我们如何排列序列，内部坏对都是固定的。 答案的唯一可控部分来自序列之间的转换。 如果序列 A 放置在序列 B 之前，则恰好有一个新的邻接关系很重要：A 的最后一个值和 B 的第一个值。当且仅当最后一个值大于 B 的第一个值时，才会出现坏对。 

这将问题简化为排序序列，以便我们最小化排列中相邻对的数量，其中`last(A) > first(B)`。 

一旦问题简化为仅根据边界对成对成本进行排序，我们就可以尝试找到在交换相邻序列的情况下稳定的排序。 如果交换两个相邻序列在正确顺序时永远不会改善答案，则存在全局贪婪排序。 

解决排序问题的一个有用方法是为每个序列分配一个键，该键捕获提前或延迟放置时可能导致问题的“高”程度。 正确的压缩结果取决于每个序列的极值。 具有较大最大值的序列过早放置是危险的，因为它更有可能超过下一个序列的起始值。 相反，最大值较小的序列尽早放置会更安全。 

这导致按照序列的第一个值和最后一个值的最大值对序列进行排序。 一旦序列按照该值的升序排序，按该顺序放置它们可以最大限度地减少连续块之间的违规数量。 以这种方式对块进行排序后，我们连接所有序列并计算内部和边界坏对。

 | 蛮力排列 | O(n!) · O(总 k) | O(总 k) | 太慢了|
 | 按键排序序列 + 合并 | O(N log n + 总 k) | O(总 k) | 已接受 |

 ## 算法演练

 ### 1.展开每个序列

 对于每位科学家，使用递归生成完整序列。 这是必要的，因为我们需要第一个和最后一个元素，并且还必须计算内部坏对。 

### 2. 计算内部坏对

 对于每个序列，从左到右扫描并计算一个值大于下一个值的次数。 这些直接影响答案，并且以后无法更改。 

### 3.提取序列边界

 对于每个序列，存储其第一个值和最后一个值。 这两个数字充分描述了序列如何与其他序列相互作用。 

### 4. 按结构键对序列进行排序

 对所有序列进行排序`max(first, last)`按递增顺序。 直觉是，具有较小极值的序列在较早放置时不太可能产生向下转换，因此应首先处理。 

### 5. 按排序顺序连接

 按排序顺序遍历序列并将其元素添加到最终列表中。 

### 6. 计数边界坏对

 在连接时，每当我们从一个序列的最后一个元素移动到下一个序列的第一个元素时，如果前一个最后一个值大于下一个第一个值，则增加答案。 

### 为什么它有效

 关键的不变量是每个序列恰好贡献一个由其最后一个元素定义的传出“边界状态”，以及恰好一个由其第一个元素定义的传入阈值。 任何排序决策仅影响这些边界值之间的比较。 

当两个序列交换时，只有它们的相对边界贡献发生变化。 按最大端点排序可确保延迟可能产生较大向下跳跃的序列，从而最大限度地减少大后缀后面跟着小前缀的频率。 这种贪婪排序将局部交换最优性与全局最优性对齐，因此一旦排序，相邻的反转交换就无法改善结果。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    seqs = []
    total = 0
    bad = 0

    for i in range(n):
        k, a1, x, y, m = map(int, input().split())
        
        arr = [a1]
        for _ in range(k - 1):
            arr.append((arr[-1] * x + y) % m)
        
        # internal bad pairs
        for j in range(len(arr) - 1):
            if arr[j] > arr[j + 1]:
                bad += 1
        
        seqs.append((max(arr[0], arr[-1]), arr[0], arr[-1], arr, i + 1))
        total += k

    # sort by structural key
    seqs.sort(key=lambda x: x[0])

    # build answer
    order = []
    prev_last = None

    for _, first, last, arr, idx in seqs:
        if prev_last is not None and prev_last > first:
            bad += 1
        order.extend((val, idx) for val in arr)
        prev_last = last

    print(bad)
    if total <= 200000:
        for val, idx in order:
            print(val, idx)

if __name__ == "__main__":
    solve()
```该解决方案首先将每个生成器扩展为其完整序列，并在单次传递中计算内部减少。 排序步骤仅使用边界信息，因此避免了将重状态带入比较。 在串联期间，唯一的额外工作是检查连续序列之间的边界转换。 

一个常见的实现陷阱是忘记在任何重新排序之前必须对内部坏对进行计数，因为它们是不变的。 另一个是错误地更新边界比较，其中只有前一个序列的最后一个元素和下一个序列的第一个元素很重要，而不是任何中间值。

 ## 边缘情况

 严格递减的序列在做出任何排序决策之前测试内部坏对是否正确累积。 例如，`5, 3, 1`无论在其他序列中的位置如何，都必须贡献两个坏对，因为这些比较是内部的。 

一个序列以非常高结束而另一个序列以非常低开始的情况测试边界处理。 如果我们将高端序列放在低端序列之前，则即使两个序列都已内部排序，也必须计算单个坏对。 

相等的边界值检验稳定性。 什么时候`last(A) == first(B)`，交换不应改变答案，并且任何确定性排序顺序都必须保持正确性，而不依赖于平局打破逻辑。
