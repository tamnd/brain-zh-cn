 ## 问题理解

 我们被要求维护两棵动态生长的带标记边缘的有根树，并在每次操作后计算“良好组合”的数量。 一个好的组合由第一棵树中的一个顶点和第二棵树中的一对顶点组成，这样从第一个树顶点**向后**到根部行走所获得的字符串与沿着第二棵树中的路径**向前**行走所获得的字符串相匹配。 操作逐步将一个新的子节点添加到具有指定字符的指定顶点，并且我们必须在每次操作后更新所有良好组合的计数。 

输入最多包含$10^5$运营。 显式比较第一棵树中每个节点的后向路径与第二棵树中所有前向路径的简单方法大约需要$O(n^3)$最坏情况下的时间，这是不可能的。 因此，我们需要一个在近线性时间内增量更新计数的解决方案。 

当新添加的节点立即形成多个新匹配时，就会出现边缘情况，因为它同时完成了第二棵树中的多个路径。 例如，将具有相同字符的子节点添加到多个节点可以匹配第一棵树中的不同后向路径。 粗心的实现可能会错过这些多个匹配项或错误地重复计算它们。 

## 方法

 暴力解决方案明确地构建了两棵树。 每次操作后，它都会枚举树一中的每个顶点和树二中的每个可能路径来比较字符串。 这种方法是正确的，但显然太慢了：对于$n = 10^5$节点，树中的路径数量是节点数量的二次方，大致给出$O(n^3)$每次更新的操作。 

关键的见解是，第一棵树中的后向路径和第二棵树中的前向路径可以表示为字符串，但直接比较字符串很慢。 Instead, we can assign **unique hash values** to each path using a rolling hash (or trie). This transforms the string comparison into an integer comparison. Each vertex's backward path hash in tree one can be stored and updated incrementally. For tree two, we maintain a **trie of forward paths**, storing counts of how many vertices correspond to each prefix. 当添加一个新顶点时，我们更新 trie 并通过来自树一的匹配反向路径的数量来增加良好组合的全局计数。 

This reduces complexity because each operation processes only the new vertex and its immediate connections. The hash/trie representation ensures that string matching and counting can be done in$O(\log n)$或者$O(1)$根据实施情况对每次更新进行摊销。

 | 蛮力 | O(n^3) | O(n^3) | O(n^2) | O(n^2) | 太慢了 |

 ## 算法演练

 1. 为一棵树维护一个数组`backward_hash[i]`表示从顶点开始的后向路径的哈希值`i`到根。 对于一个新孩子`v_new`与父母`v`和性格`c`, 计算`backward_hash[v_new] = backward_hash[v] * P + ord(c)`， 在哪里`P`是滚动哈希的合适基础。 
2. 为二棵树维护一个trie结构`forward_trie`其中每个节点包含与从根到该 trie 节点的字符串路径相对应的顶点计数。 每条边都由一个字符标记。 最初，根节点的空字符串计数为 1。 
3. 对于二号树上的每个操作，沿着父路径遍历 trie 并用新字符扩展它。 新 trie 节点处的更新计数。 
4. 维护全球地图`hash_count`计算一棵树中每个向后哈希有多少个顶点。 当在第一棵树中添加一个顶点时，增加其计数`backward_hash`。 
5. 要在操作后计算新的良好组合，如果操作是在树一上，请检查新顶点的后向哈希并添加`forward_trie_count[hash]`到总计数。 如果操作是在树二上进行的，则从新顶点向后遍历到根（或沿着 trie 向前），并且对于 trie 中的每个前缀哈希，添加`hash_count[prefix_hash]`至总数。 
6.输出每次​​操作后总的好组合。 

这确保了增量更新$O(1)$每个操作的摊销时间，因为每个顶点都被处理一次，并且仅通过其散列对总计数做出贡献。 

为什么它有效：该算法保持了以下不变式：`hash_count[h]`包含一棵匹配哈希的树中后向路径的数量`h`和`forward_trie`包含每个字符串前缀在树二中的转发路径的数量。 每次操作后的良好组合数量恰好是所有匹配哈希值的总和，保证了正确性。

input = sys.stdin.readline

class TrieNode:
    def __init__(self):
        self.children = {}
        self.count = 0

def solve():
    n = int(input())
    P = 31
    MOD = 10**9 + 7
    
    # Tree 1
    tree1 = [0]  # parent indices
    hash1 = [0]  # backward hash to root
    hash_count = {0: 1}  # empty root

        t = int(t)
