 ## 解决方案
 ## 问题理解

 我们有几位科学家，每一位科学家都会执行一系列计算任务。 每个任务都有固定的资源需求，并且在每个科学家的列表中，任务必须按照给定的顺序执行。 在不同的科学家之间，我们可以自由地以任何方式交错任务，只要我们不破坏每个科学家的内部顺序。 

我们最终构建了所有任务的一个全局序列。 当最终序列中的两个连续任务的资源使用量下降时，就会出现“坏对”，这意味着第一个任务比下一个任务需要更多的资源。 我们的目标是安排所有任务，尊重每个科学家的内部顺序，使此类任务的数量尽可能少。 

输入并未明确给出为所有任务值。 相反，每个科学家都为他们的序列提供了一个生成器。 我们得到第一个值和一个递归，该递归产生对某个数字取模的剩余值。 这迫使我们真正重建或流式传输所有任务值。 

任务总数可能很大，在最难的版本中可达数十万，因此任何明确考虑任意交错或尝试模拟所有排列的解决方案都是立即不可能的。 将所有任务视为独立项目并对它们进行排序的天真的想法也是无效的，因为它违反了每个科学家序列内的固定顺序约束。 

一个微妙的边缘情况是，两位科学家生成的序列在值顺序上严重交错，但被迫采用严格的内部顺序。 例如，如果科学家 A 的值为 [10, 1]，而科学家 B 的值为 [2, 3]，则全局排序将给出 [1, 2, 3, 10]，但这是非法的，因为 A 的顺序必须保持 10 然后 1，无论全局排序如何，这都已经强制发生了错误的转换。 这表明问题不是纯粹的排序任务。 

另一个边缘情况是科学家的序列严格递增或严格递减。 即使全局上所有的东西都可以完美地合并，内部减少也会不可避免地造成坏对，除非我们仔细地相对于其他序列定位该序列。 

## 方法

 如果我们忽略科学家之间的约束，每个任务只是一个数字，并且最小化坏对就相当于以非降序对整个多重集进行排序。 最终序列中的任何反转都会产生一对坏对，因此最佳答案将为零。 这是排序数组没有相邻递减的经典观察结果。 

困难完全来自于每个科学家的任务必须保持有序的要求。 这将问题转化为合并多个固定序列。 如果我们尝试蛮力，我们会从任何序列未穷尽的科学家那里选择下一个任务，回溯所有有效的交错。 这种交错的数量是组合的，大约是任务总数的多项式，即使对于几十个任务来说，这也远远超出了任何可行的限制。 

关键的见解是在本地重新解释目标。 每次我们在全局序列中附加下一个任务时，我们要么继续非递减转换，要么创建一个下降。 因此，成本仅取决于相邻对，并且每个选择仅影响序列中的前一个元素。 

这导致了贪婪的结构：在任何时刻，我们都维持当前最后选择的值，并决定由哪位科学家承担下一个可用任务。 唯一重要的是选择一个候选者是否会与当前尾部产生不良配对。 如果我们被迫创建一个不好的对，我们希望以一种减少未来损害的方式来做到这一点，这意味着我们应该尽可能延迟较大的值，并在它们可以不受惩罚地适合时尽早消耗较小的值。

可以通过将每个科学家的序列视为一个流来导出最佳策略，其中第一个元素始终可用，但后面的元素依赖于消耗先前的元素。 我们总是希望采用不会使当前转换恶化的最小可用下一个元素，并且只有当不存在这样的元素时，我们才会接受坏对。 

更全局的观点是，这变成了 k 个排序链（不是全局排序，而是固定顺序链）的贪婪合并，其中我们总是选择最小的可行头，更喜欢非递减转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 强力交错 | O(N!) | O(N) | 太慢了|
 | 具有优先级结构的贪婪合并 | O(N log n) | O(N log n) | O(N) | 已接受 |

 ## 算法演练

 我们将每位科学家视为其生成序列的指针。 在任何时刻，每个科学家的“前面”都是按照固定顺序的下一个未处理的任务。 

1. 生成所有序列或使用循环按需流式传输它们，仅存储当前索引和值。 我们为每个科学家维护一个指针，并知道该科学家当前的可用值。 
2. 将所有当前可用的任务放入一个结构中，使我们能够有效地挑选候选人。 每个条目都是一对（值，科学家 ID）。 最初，这包含了每个科学家的首要任务。 
3. 维护一个变量`last`它将先前选择的任务的值存储在最终序列中。 将其初始化为负无穷大，因为第一个选择不存在任何约束。 
4. 在每一步，我们决定下一个任务：

 我们首先尝试从所有可用任务中选择一个值≥`last`。 在这些有效候选者中，我们选择最小值。 这最大限度地减少了未来强制减少的可能性。 
5. 如果不存在这样的候选者，我们就被迫创建一个坏对。 在这种情况下，我们会选择总体上最小的可用值。 这使得下降尽可能小，从而为后续步骤保留了灵活性。 
6. 从科学家那里选择任务后，我们推进该科学家的指针。 如果还有更多任务，我们将使用递归生成下一个值并将其插入到可用集中。 
7.每当所选值严格小于时，我们就会增加坏对计数器`last`，然后设置`last`到所选值并继续，直到所有任务都被消耗。 

为什么这种方法有效取决于当地决策的结构。 每一步仅取决于先前选择的值和当前可用的下一个元素集。 如果存在有效的非递减延续，则选择最小的此类元素可以避免过早消耗大值，否则会在以后强制不必要的下降。 当不存在非递减选项时，任何选择都必须创建一个坏对，因此最小化所选值可以最小化未来的约束，因为它使下一个比较基线尽可能低。 

不变的是，在每个步骤之后，在符合约束且具有相同前缀长度的所有序列中，与仅在当前步骤不同的任何替代方案相比，贪婪选择永远不会增加未来不可避免的坏对的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n = int(input())
    
    # store generator state per scientist
    k = [0] * n
    a = [0] * n
    x = [0] * n
    y = [0] * n
    m = [0] * n
    
    # current index and current value per scientist
    idx = [0] * n
    cur = [0] * n
    
    heap = []
    
    total = 0
    
    for i in range(n):
        ki, a1, xi, yi, mi = map(int, input().split())
        k[i] = ki
        x[i] = xi
        y[i] = yi
        m[i] = mi
        
        idx[i] = 1
        cur[i] = a1
        
        heapq.heappush(heap, (cur[i], i))
        total += ki
    
    last = -10**18
    bad = 0
    
    while heap:
        # extract all available candidates
        tmp = []
        while heap:
            tmp.append(heapq.heappop(heap))
        
        chosen = None
        
        # try best non-decreasing candidate
        for v, i in tmp:
            if v >= last:
                chosen = (v, i)
                break
        
        # if none, take smallest overall
        if chosen is None:
            chosen = tmp[0]
        
        v, i = chosen
        
        # count bad pair
        if v < last:
            bad += 1
        
        last = v
        
        # advance scientist i
        if idx[i] < k[i]:
            nxt = (cur[i] * x[i] + y[i]) % m[i]
            cur[i] = nxt
            idx[i] += 1
            heapq.heappush(heap, (cur[i], i))
    
    print(bad)

if __name__ == "__main__":
    solve()
```该实现维护了一堆当前可用的任务，每个科学家的每个活动前缀都有一个任务。 每次我们将所有内容从堆中删除到临时列表中以决定下一个选择时，我们都会扫描不会产生减少的最小值`last`。 如果不存在，我们就回退到最小的整体。 

生成器逻辑由每个科学家直接使用递归来处理，仅在任务消耗时更新。 这避免了在不需要时显式存储完整序列。 

一个微妙的实现点是，我们在每一步都完全清空堆来评估所有候选者。 这是正确的，但不是渐近最优的； 更好的解决方案是维护两个有序结构或惰性分割。 然而，概念上的贪婪规则与该实现细节无关。 

## 工作示例

 考虑两个科学家的简单案例：

 科学家 1: [1, 5]

 科学家 2: [2, 3]

 初始堆包含(1,1)、(2,2)。`last = -inf`。 

| 步骤| 候选堆 | 选择| 最后| 坏|
 | --- | --- | --- | --- | --- |
 | 1 | 1, 2 | 1 | 1 | 0 |
 | 2 | 2, 5 | 2 | 2 | 0 |
 | 3 | 3, 5 | 3 | 3 | 0 |
 | 4 | 5 | 5 | 5 | 0 |

 该序列是完全非递减的，并且该算法始终首选最小的可行延续。 

现在考虑：

 科学家 1: [10, 1]

 科学家 2: [2, 3]

 初始堆：(10,1),(2,2),`last = -inf`。 

| 步骤| 候选堆 | 选择| 最后| 坏|
 | --- | --- | --- | --- | --- |
 | 1 | 10, 2 | 2 | 2 | 0 |
 | 2 | 10, 3 | 3 | 3 | 0 |
 | 3 | 10, 1 | 1 | 1 | 1 |
 | 4 | 10 | 10 10 | 10 10 | 10 1 |

 科学家 1 的内部减少迫使不可避免的坏对发生。 该算法将其延迟到必要时，然后在损害最小的位置支付一次。 

该轨迹表明，即使由于内部结构而不可避免地出现坏对，贪婪规则也会推迟它，同时仍然尊重约束。

 ## 边缘情况

 一个关键的边缘情况是所有可用的下一个元素都小于当前元素`last`。 在这种情况下，每一个可能的移动都会产生一个坏对，并且算法仍然必须选择最小的可用值。 例如，如果`last = 100`可用值为`[10, 20, 30]`，正确的行为是选择`10`， 不是`30`，因为两者都产生了坏对，但是`10`为未来的步骤保留较低的基线。 

另一种边缘情况是当一位科学家的序列振荡时，例如`[5, 1, 4]`。 内部下跌是不可避免的，即使仔细选择全局排序，最终也会迫使一个坏货币对出现。 该算法延迟消耗`5`直到必要时，防止过早暴露大值，否则会在序列的较早位置创建额外的坏对。 

第三种情况是许多科学家从相同的价值观开始。 贪心规则对称地对待它们，任何平局都是有效的，因为所有选择都会对`last`。
