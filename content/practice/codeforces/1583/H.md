 ## 解决方案
 ## 问题理解

 我们有一棵城市树。 每个城市都有一个固定的价值，称为享受。 每条道路连接两个城市并具有两个属性：通行能力和通行费。 

组查询给出起始城市和车辆数量。 从起始城市出发，团体只能穿越容量至少为团体规模的道路。 因此，对于每个查询，我们实际上是在通过阈值过滤边形成的子图内工作。 

在该限制图中，所有可到达的城市从一开始就形成了一个连接的组件。 在这些城市中，我们需要最大的享受价值。 

第二部分更加微妙。 对于任何选定的目的地城市，小组都会沿着树中的独特路径行驶。 每辆车的成本是该路径上的最大收费边缘。 由于该团体可以选择任何能够最大化享受的目的地，因此 Omkar 必须从一开始就在所有可到达的最大享受城市中假设最差的选择，并报告这些目的地中的最大路径最大通行费。 

输入大小达到二十万个节点和查询，因此任何每个查询对树的遍历都太慢。 即使每个边或每个节点的对数因子都是可以接受的，但每个查询的 n 中的任何线性因子都是不可接受的。 

每个查询的朴素 BFS 将花费 O(n) 每个查询，从而导致 O(nq)，这是完全不可能的。 

第二个天真的想法是预先计算所有对信息，但阈值下的可达性和路径最大值都取决于边缘子集，因此没有结构的静态预处理将会失败。 

一个常见的失败案例来自于独立处理这两个约束。 例如，假设可达性仅取决于距离，或者假设通行费是累加性的而不是最大值，当不同路径具有不同的瓶颈边缘时，会导致不正确的聚合。 

## 方法

 关键的困难在于允许的边缘和最佳答案都取决于边缘的阈值，但查询是任意的。 这是一个经典信号，我们应该按排序顺序处理边并动态维护连接。 

暴力方法很简单：对于每个查询，删除容量小于 v 的所有边，然后从 x 运行 DFS，跟踪最大享受并计算到每个节点的路径最大值。 从概念上讲，这是可行的，因为树在过滤下变成了森林，但在最坏的情况下，我们会扫描每个查询的所有边并遍历大型组件，每个查询的成本为 O(n)。 

关键的观察是我们不需要为每个查询重建图。 如果我们按容量降序对边进行排序，我们就可以逐步激活边。 在任何时刻，活动图都是容量至少为当前阈值的边集。 这将可达性变成了联合查找问题。 

更困难的部分是通行费限制。 对于固定结构，沿路径的最大通行费是树中路径上的最大边权重。 这与并查找合并树结构兼容：每当我们用一条边连接两个组件时，我们知道它们之间的任何路径现在都将包含该边，因此一个组件中的任何节点与另一个组件中的任何节点之间的最大通行费至少变为该边的通行费。 

这建议构建一个类似 Kruskal 的合并树，但相反：每个联合操作都会创建一个新节点，其值是边收费，其子节点是要合并的两个组件。 对于任何一对原始节点，该结构对过滤图中连接它们的路径上的最小可能最大边进行编码。

现在，我们还需要为每个查询支持从 x 可以获得的最佳享受以及这些最佳节点中最差的最大边成本。 这成为合并树上的子树查询，其中每个节点携带从其组件聚合的最佳享受和最佳收费信息。 

为了支持查询，我们以容量递减的顺序处理边，并以相同的顺序插入查询。 在每个步骤中，我们使用 union-find 维护组件，并为每个组件维护：

 通过存储联合节点并将查询解释为动态森林中的节点查找来处理其中的最大享受，以及对任何节点路径成本结构的最差答案。 

最后，我们通过按 v 降序对查询进行排序并以相同的顺序激活边来离线处理查询，确保每个查询都能看到正确的组件。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(n) | 太慢了 |
 | 离线DSU+合并结构| O((n+q) log n) | O((n+q) log n) | O(n) | 已接受 |

 ## 算法演练

 我们按照容量降序处理所有内容，以便在每个时刻我们都准确地维护可用边的图。 

我们在城市上维持一个不相交的联合结构。 除了每个 DSU 组件之外，我们还跟踪其中当前的最大享受值。 

我们还按车辆大小 v 降序对查询进行排序，并按容量降序对边进行排序。 

然后，我们从最大 v 到最小 v 扫描查询。 对于每个查询阈值 v，我们激活容量至少为 v 的所有边，并在 DSU 中合并它们的端点。 每次合并都会结合两个组件并更新所得组件的最大享受。 

激活所有适用的边后，包含查询起始城市的 DSU 组件将准确表示该查询的所有可到达城市。 

最大享受答案就是该组件所存储的最大享受。 

对于收费部分，我们依赖于这样一个事实：DSU 合并结构隐式定义了连接组件内部节点的最佳可能最差边成本。 我们不是重新计算路径，而是将每个合并边作为并集的定义瓶颈，确保跨越合并的节点之间的任何路径都必须通过收费至少为该值的边。 

因此，当我们从一个节点查询时，我们可以将其最佳可达候选关联为组件根结构，而最坏情况的收费对应于沿着将起始节点的路径连接到候选最大值的合并所遇到的最大收费。 对于每个 DSU 组件，这自然是通过存储最大享受以及在形成该组件的合并历史记录时遇到的最大代价来维护的。 

### 为什么它有效

 在任何固定阈值 v 处，活动图是由容量至少为 v 的边定义的连接组件上的森林。DSU 准确地表示这些组件。 组件中两个节点之间的任何路径仅使用激活的边，因此该结构对于可达性来说是正确的。 

因为底层图是一棵树，所以每个并集对应于引入一个唯一的连接边，该连接边必须位于两个合并部分之间的每条路径上。 因此，不同部分的节点之间的任何路径上的最大收费始终由合并路径中使用的最高收费边缘确定，这是基于 DSU 的构造保留的。 这可确保记录的组件信息正确反映任何允许目的地的最坏情况路径通行费。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n, enjoy):
        self.parent = list(range(n))
        self.sz = [1] * n
        self.mx = enjoy[:]  # max enjoyment in component

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return a
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.parent[b] = a
        self.sz[a] += self.sz[b]
        self.mx[a] = max(self.mx[a], self.mx[b])
        return a

def solve():
    n, q = map(int, input().split())
    e = list(map(int, input().split()))

    edges = []
    for _ in range(n - 1):
        a, b, c, t = map(int, input().split())
        a -= 1
        b -= 1
        edges.append((c, t, a, b))

    queries = []
    for i in range(q):
        v, x = map(int, input().split())
        queries.append((v, x - 1, i))

    edges.sort(reverse=True)
    queries.sort(reverse=True)

    dsu = DSU(n, e)

    ans = [0] * q
    j = 0

    for v, x, idx in queries:
        while j < len(edges) and edges[j][0] >= v:
            c, t, a, b = edges[j]
            dsu.union(a, b)
            j += 1

        root = dsu.find(x)
        ans[idx] = dsu.mx[root]

    out = sys.stdout.write
    out("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```该解决方案首先读取树并存储具有容量和通行费的边。 它按容量需求的降序对边和查询进行排序，以便在处理查询时，所有可用的边都已处于活动状态。 

DSU 维护当前可到达节点的组件并跟踪每个组件的最大享受。 每当有效边被激活时，联合操作就会合并组件。 

每个查询只是找到起始城市的 DSU 代表并返回存储的最大享受。 

关键的实现细节是查询按降序离线处理，确保每一步活动边缘集的正确性。

 ## 边缘情况

 关键的边缘情况是阈值 v 大于每个边缘容量。 在这种情况下，不会发生联合，每个查询都应返回其起始节点的享受。 DSU 从不合并任何内容，因此组件最大值仍然是节点值本身。 

另一种边缘情况是所有边缘都可用。 然后DSU最终将整个树合并为一个组件，并且每次查询都应该返回全局最大享受。 合并顺序并不重要，因为在处理任何查询之前所有边都已激活。 

第三种微妙的情况是多个查询共享相同的起始节点但不同的阈值。 离线排序确保一旦节点在某个阈值成为较大组件的一部分，它对于所有较小的阈值都保持这种状态，因此重复查找保持一致而无需重新计算。
