 ## 解决方案
 ## 问题理解

 我们有一块矩形板，其中每个单元格都被一个`X`或空。 从空单元格开始，我们只能向上或向左移动。 如果某些此类移动序列让我们离开网格，则该单元称为可退出。 问题不在于模拟这些动作。 相反，对于许多列间隔，我们必须确定可退出单元格的模式是否唯一确定该列范围内被阻止单元格的原始放置。 

每个查询都采用一组连续的列，并询问两个不同的障碍物配置是否可以产生完全相同的可退出性模式。 如果不存在歧义，我们会回答`YES`。 否则我们回答`NO`。 

产品`n × m`至多是`10^6`，因此一次性处理整个网格是可以承受的。 查询次数达到`2·10^5`，这排除了为每个查询扫描整个子网格的任何解决方案。 即使在间隔宽度上进行线性扫描也会导致粗略的结果`2·10^11`最坏情况下的操作。 查询处理时间必须是常数或对数。 

棘手的部分是了解哪种本地模式会产生歧义。 

考虑```
.X
X.
```左下单元格和右上单元格均被遮挡。 这两个障碍形成了阻碍信息传播的角落。 如果右下角的单元格也被阻止，则会出现相同的退出模式。 如果粗心的解决方案只计算阻塞的细胞，就会错过这一点。 

另一个微妙的情况是单列。```
X
.
X
```每个左右端点相同的查询都必须返回`YES`，因为没有一对相邻的列会产生歧义。 

当存在多个坏位置，但它们都位于查询间隔之外时，就会出现第三种边缘情况。```
..X.
.X..
....
```假设唯一有问题的边界位于第 2 列和第 3 列之间。查询`[1,2]`仍应返回`YES`。 整个网格的全局答案是不够的，因为不同的列范围表现不同。 

## 方法

 强力解决方案将独立检查每个查询。 对于列间隔`[l,r]`，我们可以检查相应的子网格并确定其中是否存在任何模糊结构。 这种方法是正确的，因为它直接检查查询的区域，但在最坏的情况下，每个查询几乎触及`10^6`细胞。 和`2·10^5`查询，总工作量变为`2·10^11`的操作，远远超出了极限。 

关键的观察结果是，仅一种类型的本地配置会产生歧义。 假设细胞`(i,j)`和细胞`(i-1,j+1)`都被阻止了。 那么这两个障碍物形成一个对角：```
. X
X .
```一旦这样的模式存在于两个相邻的列中，一些单元格的精确排列就不可能仅根据可退出性信息来重建。 

这意味着每个有问题的结构都可以由两个相邻列之间的边界来表示。 对于每一列`j`，我们只需要知道某行是否同时包含两者`(i,j)`和`(i-1,j+1)`被阻止。 如果是这样，则列之间的边界`j`和`j+1`很糟糕。 

查询`[l,r]`当这些列之间至少有一个错误边界时，该值是无效的。 这将问题转换为一维数组上的范围存在查询，这可以使用前缀最大值轻松处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(qnm) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(nm + q) | O(米) | 已接受 |

 ## 算法演练

 1.读取网格并创建数组`bad`长度`m+1`，最初用零填充。 
2. 对于每个细胞`(i,j)`和`i ≥ 1`和`j ≥ 1`，检查两者是否`(i,j-1)`和`(i-1,j)`包含`X`。 

这两个单元格形成对角线图案```
. X
X .
```它的存在造成了歧义。 
3. 如果存在这样的一对，则标记列边界`j`通过设置同样糟糕`bad[j]=1`。 

价值`j`表示列之间的边界`j`和`j+1`在基于一的索引中。 
4.构建前缀和数组`pref`。`pref[j]`存储位置之间的坏边界数量`1…j`。 
5. 对于每个查询`[l,r]`, 计算```
pref[r-1] - pref[l-1]
```该数量计算严格位于间隔内的不良边界。 
6. 如果计数为零，则输出`YES`。 否则输出`NO`。 

### 为什么它有效

 每次信息丢失都来自占据对角的一对对角阻塞单元。`2×2`正方形。 这样的一对使我们无法区分产生相同退出模式的几个障碍物配置。 

当查询间隔的相邻列对都不包含这样的对角线冲突时，查询间隔是可以精确确定的。 由于每个错误配置都局限于相邻列之间的单个边界，因此存储所有错误边界并回答对它们的范围查询可以准确捕获所需的条件。 区间内没有不良边界意味着不可能存在歧义，而即使存在一个不良边界也已经创建了多个有效网格。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
grid = [input().strip() for _ in range(n)]

bad = [0] * (m + 1)

for i in range(1, n):
    for j in range(1, m):
        if grid[i][j - 1] == 'X' and grid[i - 1][j] == 'X':
            bad[j] = 1

pref = [0] * (m + 1)
for j in range(1, m + 1):
    pref[j] = pref[j - 1] + bad[j]

q = int(input())
ans = []

for _ in range(q):
    l, r = map(int, input().split())
    if pref[r - 1] - pref[l - 1] == 0:
        ans.append("YES")
    else:
        ans.append("NO")

sys.stdout.write("\n".join(ans))
```嵌套循环扫描每个`2×2`间接平方。 每当右上角和左下角的单元格都被阻挡时，这些列之间的边界就会出现问题。 

数组`bad`使用从一开始的边界编号。 位置`j`对应于列之间的边框`j`和`j+1`。 这种索引很容易出错。 查询`[l,r]`包含边界`l,l+1,…,r-1`，这解释了表达式`pref[r-1]-pref[l-1]`。 

整数溢出不是问题，因为所有计数最多`m≤10^6`。

 | 测量 | 复杂性 | 说明|

 ## 边缘情况

 单列查询不包含相邻列对。```
3 1
X
.
X
1
1 1
```这`bad`数组保持为零，因为根本没有边界。 查询计算`pref[0]-pref[0]=0`，所以答案是`YES`。 

考虑对角线冲突```
2 2
.X
X.
1
1 2
```在预处理期间，在`(1,1)`我们发现左下和右上的单元格都是`X`， 所以`bad[1]=1`。 查询评估`pref[1]-pref[0]=1`，生产`NO`。 

最后，假设冲突位于查询区间之外：```
3 4
..X.
.X..
....
2
1 2
2 4
```仅边界 2 被标记为坏。 为了`[1,2]`，差异是`pref[1]-pref[0]=0`，所以答案是`YES`。 为了`[2,4]`，差值变为`pref[3]-pref[1]=1`，生产`NO`。 该算法正确地隔离每个区间，而不是使用单个全局决策。
