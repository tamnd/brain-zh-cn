 ## 解决方案
 ## 问题理解

 我们得到一个连通的无向图，其中每条边都有一个代表拥塞的正权重。 从节点 1 到节点 n 的路径不以通常的方式评估。 不是将所有边权重相加，而是仅沿着路径的两个最大边权重起作用。 如果路径包含至少两条边，则其成本定义为该路径上最大和第二大边权重的总和。 如果路径恰好包含一条边，则成本就是该边的权重。 

任务是选择从 1 到 n 的任何路径来最小化这种特殊成本。 

约束很大：最多 3×10^5 个顶点和最多 10^6 个边。 这立即排除了任何尝试枚举所有路径甚至对路径进行多状态动态编程的解决方案。 即使 O(m log m) 是可以接受的，但任何边或顶点是二次的则不可以。 

一个微妙的点是，目标仅取决于路径中前两个边缘权重，而不是路径的总和或长度。 这意味着长路径本质上并不是坏事，只要它们的两个最大边缘很小即可。 

一些边缘情况值得明确。 

一条边是最佳路径是一条边的情况。 例如，如果存在权重为 5 的直接边 (1, n)，并且所有其他路径都使用权重至少为 10 和 20 的边，则答案为 5，而不是 10 + 20。 

另一种情况是最优路径有很多边但只有两个大瓶颈。 例如，路径 1 → a → b → n，其中边权重为 1、100、2。无论路径长度如何，成本均为 100 + 2 = 102。 

第三个陷阱是假设最短路径风格的思维有效。 标准 Dijkstra 跟踪每个节点的一个最佳值，但这里可以根据迄今为止看到的最大边，在多个“状态”中到达一个节点。 幼稚的状态扩展变得太大而无法在约束下直接管理。 

## 方法

 一个蛮力的想法是处理从 1 到 n 的每个简单路径，计算其两个最大的边权重，并取最小值。 这在原则上是正确的，因为它完全符合定义。 然而，一般图中简单路径的数量是指数级的，因此即使生成它们也是不可能的。 即使在边缘方面限制最短路径也无济于事，因为如果减少第二大瓶颈，较重的边缘可能会更好。 

一种更结构化的尝试是使用类似 Dijkstra 的松弛，其中每个状态不仅存储当前节点，还存储迄今为止看到的最大和第二大边。 从状态 (u, max1, max2) 开始，遍历边 w 通过将 w 插入到前两个结构中来生成一个新对。 这在逻辑上是正确的，但是状态数量爆炸：max1和max2可以取很多值，每个节点可能会积累很多无法比较的状态。 在最坏的情况下，在 10^6 条边下这是不可行的。 

关键的观察是我们实际上不需要跟踪完整路径历史。 答案仅取决于所选路径中的最大边缘和第二最大边缘，因此我们可以尝试“猜测”这两条边缘是什么。 

假设我们固定一个阈值W，问：是否有一条从1到n的路径，其最大边权值至多为W？ 这是边 ≤ W 的子图上的标准连通性查询。现在假设我们还想控制第二大边。 如果我们选择路径中最大的边作为权重 W 的某个边，那么第二大边必须尽可能小，同时如果我们删除该边，仍然允许两个端点之间的连接。

这建议进行结构重构：对于每条边，想象它是答案路径中的最大边。 如果我们强制这条边为最大值，我们只需要使用权重≤W的边连接它的端点，但不包括边本身，然后确保在该连接路径中最大边被最小化。 这将问题简化为最小生成树样式推理和离线连接的组合。 

一种更清晰的查看方式是按权重对边缘进行排序。 当我们按升序添加边时，我们保持连接性。 此时，我们添加一条连接组件 A 和 B 的权重为 w 的边，任何使用该边作为最大值的路径都必须仅使用边 ≤ w 将 A 中的某个节点连接到 B 中的某个节点。 那么，最好的第二大边是在添加该边之前沿着 A 和 B 并集内的任何路径的最小可能最大边。 这正是最小生成树结构查询。 

这导致了基于 DSU 的 Kruskal 过程，但增加了一个值，该值跟踪每个组件迄今为止看到的最佳可能的“内部第二瓶颈”，并且当通过边 w 合并组件时，我们更新 w 的候选答案加上两侧之间的最佳内部连接成本。 

这将问题转化为通过并查找并仔细记录最小内部最大边路径的排序边的单次遍历，从而产生 O(m α(n)) 解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对所有路径进行暴力破解 | 指数| O(n) | 太慢了 |
 | 用 (node, max1, max2) | 状态 Dijkstra O(m log m · 状态爆炸) | O(米) | 太慢了 |
 | Kruskal + DSU 增强 | O(m α(n)) | O(m α(n)) | O(n) | 已接受 |

 ## 算法演练

 我们按权重递增的顺序对所有边进行排序。 直觉是，当我们考虑权重为 w 的边时，我们正在决定 w 是否可以作为最佳答案中的最大边，并且我们想知道可以与其配对的最佳可能的第二大边。 

我们在顶点上维护并查找结构，其中组件仅使用到目前为止处理的边来表示连接性。 对于每个组件，我们维护一个代表值，跟踪迄今为止看到的最佳内部“第二个瓶颈候选者”。 具体来说，该值表示组件内已使用较早边连接的任何两个节点之间的任何路径上的最小可能最大边权重。 

我们按升序处理边。 当我们处理一条边 (u, v, w) 时，我们会查看包含 u 和 v 的分量 Cu 和 Cv。 

如果 Cu 和 Cv 不同，这条边可以将它们连接起来。 任何使用该边作为最大值的路径都必须将其与完全位于 Cu ∪ Cv 内且使用权重 ≤ w 的边的路径组合起来。 最佳第二大边由合并前 Cu 和 Cv 之间的最佳内部连接路径确定。 我们使用存储的组件值来计算候选答案 w 加上该内部值，并更新全局最小值。 

处理完候选数据后，我们将 Cu 和 Cv 结合起来，合并它们存储的组件信息，以便未来的边缘看到更新的连接。 

我们还单独考虑路径仅使用一条边的情况。 为此，答案就是直接连接 1 和 n 的最小边权重，因此我们也跟踪它。 

### 为什么它有效

 当我们处理权重为w的边时，任何最大边为w的最优路径必须具有权重≤w的所有其他边。 通过对边进行排序，所有此类边都已存在于 DSU 结构中。 第二大边恰好是最大边的两个端点之间的最佳可能连接路径内的最差边。 DSU 增强保证对于同一组件中的任意两个顶点，我们保留足够的信息来恢复连接它们所需的最小可能的最大内部边，因此在考虑最大边时，每个候选对（最大边、第二最大边）仅被评估一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n + 1))
        self.sz = [1] * (n + 1)
        self.best = [10**30] * (n + 1)

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b, w, ans_ref):
        ra = self.find(a)
        rb = self.find(b)
        if ra == rb:
            return

        # candidate: w + best internal connection between components
        cand = w + min(self.best[ra], self.best[rb])
        ans_ref[0] = min(ans_ref[0], cand)

        if self.sz[ra] < self.sz[rb]:
            ra, rb = rb, ra

        self.p[rb] = ra
        self.sz[ra] += self.sz[rb]

        # merge component info
        self.best[ra] = min(self.best[ra], self.best[rb], w)

def solve():
    n, m = map(int, input().split())
    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((w, u, v))

    edges.sort()

    dsu = DSU(n)
    ans = [10**30]

    for w, u, v in edges:
        dsu.union(u, v, w, ans)

    # also consider direct single-edge path 1-n
    for w, u, v in edges:
        if (u == 1 and v == n) or (u == n and v == 1):
            ans[0] = min(ans[0], w)

    print(ans[0])

if __name__ == "__main__":
    solve()
```该实现以按权重对边进行排序为中心，以便当我们处理边时，所有较轻的边已经形成了推理第二大边所需的连接结构。 DSU 维护按尺寸联合的组件尺寸以及总结内部连接质量的最佳辅助值。 并集操作是唯一真正计算发生的地方：我们尝试形成一条最大边是当前边权重的路径，并将其与两侧的最佳内部结构相结合。 

一个微妙的实现细节是单独处理单边路径。 如果没有这一点，1 和 n 之间的直接边缘可能会被人为构建的两条边缘解释所掩盖。

 ## 边缘情况

 一种边缘情况是通过从 1 到 n 的直接边缘获得最佳答案。 该算法在处理所有边缘后显式检查这一点。 对于输入：```
2
1 2 7
```DSU 没有任何改进，最终检查正确返回 7。 

另一种边缘情况是最佳路径恰好需要两个重边缘并且所有其他边缘都非常小。 排序处理确保当考虑较重的边缘时，所有较轻的边缘都已在 DSU 中，因此内部最佳值正确反映了第二大候选值。 

第三种边缘情况是完全连接的小图，其中存在多个替代的双边最大值。 因为每条边都被视为潜在最大值一次，所以不会错过任何候选对，并且所有此类构造的最小值都保留在全局答案中。
