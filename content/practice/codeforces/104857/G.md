 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，表示一系列课程的出勤情况。 条纹是由 1 组成的最大连续段，意味着以零或字符串末尾为界的连续参加的课程块。 

我们最多可以翻转`m`零变为一。 执行这些翻转后，字符串会发生变化，因此条纹集也会发生变化。 在所有可能的结果字符串中，最多可达`m`翻转时，我们关心所有条纹的长度，按非递增顺序排序。 目标是最大化第 k 个最大条纹的长度。 如果少于`k`条纹，第 k 个值定义为`-1`。 

关键对象不仅仅是最长的段，还有多个段的顺序。 自从`k ≤ 5`，我们只关心前几条条纹，这是一个很强的结构性限制。 

限制因素`n ≤ 2 × 10^5`和`m ≤ n`意味着任何解必须接近线性或至多`O(n log n)`。 任何尝试所有翻转零选择或显式枚举所有结果配置的方法都会发生组合爆炸。 

一个天真的解释是：选择哪个`m`零来翻转，重新计算所有条纹，并跟踪第 k 个最大的条纹。 零的选择个数是`C(n, m)`，即使对于小规模来说也是不可行的`n`。 

一个稍微好一点但仍然不正确的贪心想法是始终通过翻转相邻的零来扩展现有的最大条纹。 这失败了，因为对于第 k 个位置来说，合并两条较小的条纹比扩展一条大的条纹更好。 

当多个中等连胜争夺排名时，会出现微妙的边缘情况。 

例子：```
s = 10100101, m = 2, k = 2
```如果我们贪婪地扩展最长的条纹，我们可能会创建一个长块并保留其他小的块，但最佳配置可能会合并或创建两个平衡的条纹以最大化第二大的条纹。 

当条纹被不同大小的间隙分开时，会出现另一种失败情况。 在一个区域中花费翻转可以减少其他地方可用的条纹数量，这直接影响 k 阶统计量。 

关键的困难在于翻转不仅会增加长度，还会合并片段，从而以非局部方式改变条纹的数量。 

## 方法

 暴力法是选择最多`m`零位置，翻转它们，重建结果字符串，提取所有最大的一游，对它们进行排序，并评估第 k 个最大的。 这是正确的，因为它直接遵循定义。 然而，选择零的子集已经引发了指数行为。 甚至忽略选择，根据配置成本重新计算条纹`O(n)`，使得总数远远超出了可行的范围。 

结构观察来自于相反的视角：我们不是选择要翻转哪些零，而是考虑构建 k 个最佳条纹以及如何在它们之间分布翻转。 自从`k ≤ 5`，“重要对象”的数量很少。 这表明对恒定数量的目标进行动态规划或贪婪分配。 

我们可以将问题重新定义为试图最大化候选值`L`计算第 k 个最大的条纹并检查可行性。 如果我们确定第 k 个条纹的长度应该是多少，我们可以问是否有可能创建至少`k`不相交的线段，其长度至少在最多以下的适当值`m`翻转。 

这自然会导致对答案进行二分搜索。 对于固定阈值`L`，我们尝试构建至少尽可能多的长度条纹`L`尽可能使用贪婪扩张。 每个条纹都需要收集 1，并可能在其间转换 0，并且合并附近的片段始终是最佳选择，因为它可以避免在碎片上浪费翻转。 

关键的贪婪想法是形成一条长度的条纹`L`，我们应该始终从现有的长度延伸并吸收附近的零，直到达到所需的长度。 一旦形成连胜，我们就继续前进并重复。 这是最优的，因为任何最优解决方案都可以重新排列，以便每个选定的条纹都是最大且不重叠的。 

自从`k`很小，我们只需要知道是否至少可以获得`k`给定的有效条纹`L`。 如果是，我们尝试增加`L`。

 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 二分查找+贪心可行性| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们通过二分搜索答案来解决问题，其中谓词检查我们是否至少可以获得`k`条纹长度至少`L`。 

1.我们设置一个搜索范围`L`从`0`到`n`。 每个值代表条纹的目标最小长度。 目标是找到最大值`L`这样至少`k`长度的条纹`L`可以形成。 
2.对于固定的`L`，我们从左到右扫描字符串，贪婪地构建条纹。 当我们遇到可以扩展到有效条纹的段时，我们使用零作为翻转来连接或扩展它。 这是使用滑动窗口样式扩展来完成的。 
3. 扫描过程中，每当我们积累至少一条有效长度的条纹`L`，我们完成它并从下一个位置重新开始。 这可以防止重叠并确保条纹之间的独立性。 
4. 我们维护一个计数器来记录我们已经使用了多少次翻转。 如果在任何时候所需的翻转次数超过`m`，我们提前停止并拒绝这个`L`。 
5. 如果我们设法构建至少`k`条纹，我们标记`L`尽可能尝试更大的值。 否则，我们会减少搜索空间。 

贪婪构造起作用的原因是任何最佳解决方案都可以进行转换，以便每个选定的条纹尽可能左对齐。 延迟翻转或重新分布它们只会减少可实现的不相交段的数量。 

## 为什么它有效

 对于固定目标长度`L`，我们本质上是打包尽可能多的长度-`L`尽可能将其分段到字符串中，其中零充当间隙，可以使用翻转来支付。 贪婪扫描总是首先消耗最早的可能段，这为后续段留下最大的剩余空间。 任何推迟分段的替代安排只会将其成本向右推，而不会减少所需的翻转次数，因此它无法提高有效条纹的总数。 

二分查找是有效的，因为可行性是单调的：如果我们可以形成`k`长度的条纹`L`，那么我们也可以将它们形成任何更小的长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(s, n, m, k, L):
    i = 0
    used = 0
    cnt = 0

    while i < n:
        if s[i] == '0':
            i += 1
            continue

        j = i
        used_local = 0
        length = 0

        while j < n and length < L:
            if s[j] == '1':
                length += 1
            else:
                if used + used_local + 1 > m:
                    break
                used_local += 1
                length += 1
            j += 1

        if length >= L:
            used += used_local
            cnt += 1
            i = j
        else:
            i += 1

        if used > m:
            return False
        if cnt >= k:
            return True

    return cnt >= k

def solve():
    n, m, k = map(int, input().split())
    s = input().strip()

    lo, hi = 0, n
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(s, n, m, k, mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    if k > n:
        print(-1)
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```解决方案从对答案进行二分搜索开始，因为谓词“我们能否实现长度至少为 L 的 k 个条纹”是单调的。 这`can`函数模拟从左到右贪婪地构建条纹。 

里面`can`，我们扫描字符串，每当我们点击`'1'`，我们尝试从那里开始延长连续记录。 展开式内的零被视为所需的翻转。 我们跟踪当前连胜候选者在全局和本地使用了多少次翻转。 一旦条纹达到长度`L`，我们承诺它，将其翻转添加到全球预算中，然后继续前进。 

重要的实现细节是，一旦位置包含在连胜中，我们就永远不会重复使用它。 这确保条纹保持不相交，与定义匹配。 

当我们超过时，我们也会提前退出`m`或已经形成`k`条纹，使每次检查的运行时间保持线性。

 ## 边缘情况

 一种边缘情况是当字符串已经包含少于`k`条纹，但可以使用翻转合并。 例如：```
s = 10001, m = 1, k = 1
```该算法扩展到中心间隙，使用一次翻转，并正确地形成一条长条纹。 贪婪扫描合并两端，因为它总是尝试从最早的有效位置开始扩展。 

另一种情况是当`k`即使在完全转换后也大于可能的条纹数量：```
s = 00000, m = 2, k = 3
```即使将两个零变成一后，我们最多也可以创建两条条纹，所以答案是`-1`。 可行性检查从未达到`cnt >= k`，所以所有`L > 0`失败。 

第三种情况是翻转丰富但条纹结构支离破碎：```
s = 1010101, m = 10, k = 3
```在这里，最优策略将所有内容合并成一条长线，但由于`k = 3`，我们被迫分裂，答案就受到可以存在多少不相交段的限制，而不是可用翻转的总数。
