 ## 解决方案
 ## 问题理解

 我们得到了一系列气球颜色，其中每个气球都有一个由短小写字符串表示的颜色。 任务是确定是否存在严格超过气球总数一半的颜色。 如果存在这种颜色，我们就输出它。 否则，我们输出失败字符串“uh-oh”。 

该结构本质上是关于多组字符串中的主导地位。 除了确定严格多数元素是否存在以及如果存在则返回之外，我们不会被要求列出频率或计算其他任何内容。 

输入大小最多可达 100000 个字符串，每个字符串的长度最多为 10。这立即表明，任何比较每对字符串或重复扫描整个列表以查找每个候选的算法都会太慢。 使用散列在线性时间内计算频率的解决方案是合适的，因为操作总数约为 100000 次插入和查找，这完全在典型限制内。 

当没有颜色超过 50% 阈值时，就会出现微妙的边缘情况。 例如，如果输入是三种不同的颜色，如红色、蓝色、黄色，每种颜色出现一次，则没有输出颜色合格，答案必须是“uh-oh”。 另一种边缘情况是正好有一半的气球是一种颜色。 例如，在 n = 4 中，如果某种颜色恰好出现 2 次，则不满足严格的“超过一半”要求，因此不应接受。 

另一个重要的情况是，当存在多种颜色但其中一种颜色几乎没有超过阈值时，例如 5 个气球，计数为红色 = 3，绿色 = 2。只有主颜色有效，即使其他颜色可能很频繁。 

## 方法

 一种直接的方法是通过扫描整个列表来计算每种颜色的出现次数，并且对于每种不同的颜色，通过另一次扫描重新计算其频率。 这需要每种颜色执行 O(n) 次工作，在最坏的情况下（所有颜色都不同）会导致 O(n^2) 工作量。 当 n 达到 100000 时，这太慢了。 

关键的观察是我们只关心相同字符串上聚合的频率。 一旦我们在读取输入时维护了频率图，我们就可以确定单次传递中的最大频率。 这将问题简化为计数，然后检查最大计数是否超过 n/2。 

另一种观点是，这是一个经典的字符串多数元素问题。 虽然像 Boyer-Moore 多数投票这样的算法存在，但它们在这里是不必要的，因为在给定约束的情况下，哈希映射提供了更简单且同样有效的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力计数每种颜色| O(n^2) | O(n^2) | O(1) | O(1) | 太慢了 |
 | 频率图| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们维护一个字典，存储读取输入时每种颜色出现的次数。 

1. 初始化一个空的哈希图来存储颜色的频率。 这允许平均每个字符串的恒定时间更新和查询。 
2. 逐一读取每个气球颜色并在地图中增加其计数。 这确保了在输入处理结束时，我们拥有完整的频率信息，而无需额外的传递。 
3. 在我们更新地图时跟踪频率最高的颜色。 这避免了事后扫描地图并保持解决方案严格线性。 
4.处理完所有颜色后，将最大频率与n除以2进行比较。如果严格大于，则输出相应的颜色。 
5. 否则，输出“uh-oh”。 

我们使用严格比较的原因很关键：等于一半不满足问题条件。 

### 为什么它有效

在处理过程中的任何时刻，频率图都准确地反映了每种颜色迄今为止出现的次数。 因此，最后频率最大的颜色是整个数据集的全局最大化。 由于正确性的条件仅取决于单个值是否超过 n/2，因此识别最大频率足以决定答案。 序列的其他结构属性并不重要。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    freq = {}
    best_color = ""
    best_count = 0

    for _ in range(n):
        c = input().strip()
        freq[c] = freq.get(c, 0) + 1

        if freq[c] > best_count:
            best_count = freq[c]
            best_color = c

    if best_count > n // 2:
        print(best_color)
    else:
        print("uh-oh")

if __name__ == "__main__":
    solve()
```解决方案维护一个字典`freq`来计算出现次数。 变量`best_count`跟踪迄今为止看到的最大频率，并且`best_color`记住哪种颜色实现了这一点。 这避免了第二次遍历字典。 

一个常见的错误是使用`>= n // 2`而不是`> n // 2`，它错误地接受恰好出现一半时间的颜色。 另一个潜在的陷阱是在读取字符串时忘记去除换行符，这会导致相同的颜色被视为不同的键。

 ## 边缘情况

 一种边缘情况是所有颜色都不同。 频率图仍然记录每种颜色一次，但没有值超过n/2。 对于输入：```
4
a
b
c
d
```该算法将每个频率跟踪为 1，并且由于 1 不大于 2，因此它正确地输出“uh-oh”。 

另一种情况是多数存在但出现在不连续的位置。 例如：```
7
x
y
x
z
x
x
y
```x 的频率变为 4，超过 7/2 = 3.5。 尽管出现的情况是分散的，但映射会正确聚合，并且算法会输出 x。
