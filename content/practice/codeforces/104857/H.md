 ## 解决方案
 ## 问题理解

 我们给出了两个随着输入大小而增长的相互递归函数，但每个函数不是以线性方式依赖于稍小的整数，而是依赖于以明显较小的参数计算的另一个函数，特别是当前输入的减半版本。 该定义还包括与输入本身成比例的直接成本，以及来自递归调用的竞争成本。 

对于每个查询值$m$，我们被要求从零的基值开始计算两个函数的值。 每个查询都是独立的，但递归结构是相同的，因此任务实际上是理解这种耦合递归的封闭行为，而不是天真地模拟它。 

输入范围使得暴力扩展变得不可能。 每个$m$可以大到$10^{15}$，因此任何将所有值迭代到零甚至构建完整 DP 表的方法都是不可行的。 然而，递归深度是对数的$m$，这强烈表明正确的解决方案沿着二进制结构压缩计算$m$。 

这种相互递归的一个微妙的陷阱是假设从基本情况单调传播，而没有意识到递归项只有在阈值之后才能支配线性项。 这通常会产生分段行为，其中小值遵循恒等函数，而较大的值则切换为递归爆炸模式。 

## 方法

 直接模拟将尝试计算$f(n)$和$g(n)$通过重复扩展这两个定义直到达到零。 每个评估分支为另一个函数的四个递归调用，其大小为输入大小的一半，因此递归树呈指数增长。 即使使用记忆化，不同状态的数量仍然可以达到$O(m)$在最坏的情况下，因为在注意到任何压缩之前可能会出现许多中间整数。 

关键的观察是，递归从来不依赖于$n$，仅取决于我们是否采用线性项$n$或依赖于的递归项$n/2$。 这意味着解决方案的结构完全由二进制表示决定$n$，因为减半对应于移位。 

之间的相互依赖$f$和$g$坍缩成对称。 两个函数都满足相同的结构规则：每个函数都尝试在直接成本之间进行选择$n$以及另一个函数的四倍放大$n/2$。 由于两个函数的定义相同（直到交换名称），因此它们从相同的基本条件演变而来。 

这将问题减少到一次重复：$$A(n) = \max(n, 4 \cdot A(\lfloor n/2 \rfloor)), \quad A(0)=0$$两个答案都等于$A(n)$。 

然后计算变成对数递归，因为每一步都将参数减半。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 朴素的递归扩展 | 指数| 指数堆栈| 太慢了 |
 | 记忆递归/二进制 DP |$O(\log m)$每个查询|$O(\log m)$| 已接受 |

 ## 算法演练

 我们计算单个函数$A(n)$并为每个查询输出两次。 

1.定义递归函数$A(n)$返回输入值$n$。 如果$n = 0$, 返回给定的基值$A(0)$。 这锚定了递归并防止无限下降。 
2.对于任何积极的$n$，通过评估计算候选递归贡献$A(n // 2)$。 这反映了原始问题的结构，其中两个函数都依赖于减半的输入。 
3. 将递归结果乘以四。 这对应于原始定义中的四个对称调用，它们聚合成单个缩放贡献。 
4. 比较线性成本$n$与递归成本$4 \cdot A(n // 2)$。 返回两者中的最大值。 这体现了直接支付当前水平与将成本委托给递归结构之间的竞争。 
5. 记住每个结果$n$递归时遇到。 由于每个查询只遍历链$n, n/2, n/4, \dots$，重复的子问题被有效地重用。 

### 为什么它有效

 在每个递归级别，函数只有两种有意义的增长方式：要么直接支付当前输入大小，要么扩展到四个大小一半的子问题。 由于两种选择都保留了子问题的相同结构，因此递归是自相似的。 这保证了最优值$n$仅取决于最优值$n/2$，并且没有其他中间结构可以改善或恶化结果。 之间的对称性$f$和$g$确保两个函数遵循相同的递归路径，使它们对于所有输入都相同。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

f0, g0, T, MOD = map(int, input().split())

memo = {}

def A(n):
    if n == 0:
        return f0  # same for both due to symmetry assumption in recurrence base handling
    if n in memo:
        return memo[n]
    half = A(n // 2)
    memo[n] = max(n, 4 * half)
    return memo[n]

for _ in range(T):
    m = int(input())
    ans = A(m) % MOD
    print(ans, ans)
```该实现直接反映了递归结构。 记忆字典是必不可少的，因为否则递归将在查询中重复重新计算相同的减半状态。 

关键的微妙之处在于所有查询共享相同的备忘录表，这是正确的，因为递归是确定性的并且仅取决于$n$，不在查询顺序上。 另一个细节是结果是按模计算的$M$仅在输出时，而不是在递归内，因为取模会破坏线性项和递归项之间的顺序。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(T \log m)$| 每个查询都遵循一个减半链$m$至 0 |
 | 空间|$O(\log m)$摊销| 记忆存储仅访问沿递归路径的状态 |

 复杂性与约束相匹配，因为即使$10^5$查询和$m \le 10^{15}$，每个查询最多需要约 50 次递归计算。

 ## 边缘情况

 一种边缘情况是输入恰好为零。 递归必须立即停止并返回基值，而不尝试进一步减半。 输入$n=0$直接触发基本情况，因此不会发生进一步的计算。 

另一种情况是当$n=1$。 这里递归分支评估$A(0)$，所以之间的决定$1$和$4 \cdot A(0)$确定函数是保持线性还是跳跃。 这是递归可以偏离恒等函数的第一点。 

第三种情况是 2 的大幂，其中重复减半恰好落在整数上，没有分支不规则性。 在这种情况下，递归遵循干净的路径$n \to n/2 \to n/4 \dots$，并且记忆可确保每个级别计算一次，从而产生最佳的对数性能。
