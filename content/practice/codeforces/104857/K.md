 ## 解决方案
 ## 问题理解

 我们得到一棵代表校园的树，其中每个节点都是一栋建筑物，并且每个建筑物都有一个正的重要性值。 我们必须通过删除一些边将树分成几组。 每个组必须在原始树中连接，因此每个组都是顶点分区的连接组件。 

对于每个群体，其对答案的贡献都是以一种稍微不寻常的方式定义的。 如果该组至少包含两个节点，我们会查看其中的所有权重并取第二大的权重。 如果该组只有一个节点，则其贡献为零。 目标是对树进行分区，以使这些组贡献的总和最大化。 

关键的结构限制是我们只能切割树中的边。 这意味着每个有效的解决方案都对应于选择一些要删除的边，从而生成一个森林。 

约束 n 高达 5 × 10^5 立即排除任何尝试枚举分区甚至推理每个节点子集的行为。 任何解决方案都必须接近线性或线性对数，因为 O(n log n) 或 O(n) 是唯一现实的范围。 

如果我们假设大权重应该始终形成自己的组，则会出现微妙的故障模式。 这种直觉是错误的，因为第二大元素才是重要的，因此隔离一个区域的最大值实际上会破坏贡献，除非第二大元素保留在其他地方。 

例如，考虑权重为 10, 9, 1 的链 1-2-3。如果我们将所有节点放在一起，则贡献为 9。如果我们拆分 {10,9} 和 {1}，我们会得到 9 + 0 = 9。如果我们拆分所有单例，我们会得到 0。但是如果我们错误地拆分为 {10,1} 和 {9}，我们会得到 1 + 0 = 1，这实际上更糟。 因此分组决策取决于结构，而不仅仅是排序权重。 

真正的困难在于，每个区域的分数仅取决于其前两个权重，这表明每个区域本质上都是由其第二大元素“锚定”的，而除了启用第二个位置之外，最大元素是无关的。 

## 方法

 暴力方法会尝试所有方法来切割边缘，将树的所有分区生成为连接的组件。 对于每个分区，我们计算每个组件的第二大值。 即使我们避免从头开始重新计算并维护组件统计信息，切割边缘的方法数量也是 2^(n−1)，因为每条边缘要么被切割，要么不被切割。 即使 n = 30，这也会变得天文数字般大，因此这个方向立即不可能。 

观察的关键是倒转观点。 我们不考虑组件，而是考虑每个节点如何作为某个区域的最大或第二大元素做出贡献。 第二大元素是唯一做出贡献的元素，这表明每个区域必须恰好有一个“活跃”节点来扮演第二大元素的角色。 

现在考虑一个权重为 w[u] 的节点 u。 如果 u 是其区域的第二大元素，则该区域必须包含至少一个具有严格更大权重的节点，该节点充当最大值。 该较大的节点必须位于同一连接组件中的某个位置。 这创建了一种方向关系：u 处每个选定的“第二最大角色”必须通过将 u 附加到某个祖先或更高权重的节点来支持。 

这自然会导致通过减少权重来对节点进行排序并按该顺序处理它们。 当我们处理一个节点时，我们决定它是否成为某个区域的第二大贡献者，并将其向上连接到一个更高权重的节点，该节点将作为其最大支持。 

树结构确保连接约束减少到维持有根树中沿父子边缘的连接。 通过任意对树进行生根，我们可以考虑将节点链接到已处理的较高权重节点。

管理此问题的标准方法是维护一个结构，该结构跟踪每个节点有多少活跃子节点已经通过形成贡献而被“消耗”。 每次我们将一个节点分配为第二大元素时，我们都会有效地将其与权重较高的节点“配对”，并且这种配对会消耗树中的一条边路径。 最优策略变得贪婪：总是将一个节点附加到类似 DSU 的结构中最近的可用的较高权重祖先，通过处理引起的树排序。 

最终的效果是，当且仅当每个节点可以向上匹配时，每个节点作为第二大元素只贡献一次，并且匹配尊重树的连通性。 最优解决方案简化为按权重排序的有根树上的最大匹配式贪婪过程。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 权重排序贪婪 + 树链接 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们以任意节点（通常为 1）作为树的根，以便每个节点都有父子结构。 我们还按权重降序对所有节点进行排序，以便在处理节点时，已经考虑了所有潜在的“支持最大”节点。 

我们在有根树上维护一个 DSU 或父指针结构，使我们能够快速爬到仍然“可用”支持配对的最近祖先。 

1. 按权重递减对节点进行排序。 这确保了当我们处理一个节点时，所有具有较大权重的节点都已被考虑并且有资格充当区域的最大值。 
2.维护树节点上的DSU结构，最初每个节点都是它自己的集合。 DSU 代表尚未完全用于形成区域的最接近的可用祖先。 
3. 按排序顺序处理节点。 对于节点 u，我们尝试将其指定为某个区域的第二大元素。 
4. 为此，我们尝试在 u 的父链上使用 DSU“find”在根树中找到 u 的可用祖先 v。 这个v代表一个权重较高的节点，可以作为u区域的最大值。 
5. 如果存在这样的 v，我们将答案增加 w[u]，因为 u 成为有效区域的第二大元素。 
6. 使用 v 支持 u 后，我们将 u 合并到 DSU 术语中的 v 中，这意味着 u 不再可以独立用作支持节点。 这保留了每个节点最多被用作支撑结构一次的不变量。 
7. 继续，直到处理完所有节点。 

关键思想是，每个成功的配对都对应于形成或扩展一个区域，其中 u 保证是第二大元素，因为所有早期处理的节点都具有更高的权重并确保存在有效的最大值。 

### 为什么它有效

 在该过程中的任何时刻，DSU 确保每个节点都指向仍然能够充当区域最大值的最近祖先。 因为节点是按权重递减顺序处理的，所以当我们分配节点 u 时，我们找到的任何祖先都已经具有严格更大的权重。 这保证了 u 作为第二大元素始终有效。 每个节点在这样的角色中最多使用一次，因为一旦合并，就不能再独立选择。 这在贡献和有效支持最大值之间强制执行一对一的结构，该结构与区域权重的定义完全匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))

    def find(self, x):
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a != b:
            self.parent[a] = b

n = int(input())
w = [0] + list(map(int, input().split()))
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

parent = [0] * (n + 1)
order = []
stack = [1]
parent[1] = -1

while stack:
    u = stack.pop()
    order.append(u)
    for v in g[u]:
        if v == parent[u]:
            continue
        parent[v] = u
        stack.append(v)

nodes = list(range(1, n + 1))
nodes.sort(key=lambda x: -w[x])

dsu = DSU(n)
ans = 0

for u in nodes:
    p = parent[u]
    if p == -1:
        continue
    v = dsu.find(p)
    if v != 0:
        ans += w[u]
        dsu.union(u, v)

print(ans)
```该解决方案首先构建树的有根表示，以便每个节点都有一个父指针。 这是必要的，因为贪婪策略依赖于向上移动到更高权重的候选者。 

DSU 的使用方式有点不标准：它不代表原始边缘的连接性，而是代表未来配对的祖先的可用性。 当一个节点作为配对的一部分被使用时，它会向上合并，以便将来的查询跳过它。 

主循环从最高权重到最低权重处理节点。 这种排序至关重要，因为它保证每当我们向上附加节点时，父节点已经能够成为有效区域中的“最大值”。 

仅当节点成功找到可用的祖先时，答案才会累积，因为只有这样它才能充当第二大元素。 

## 工作示例

 考虑一棵小树：

 输入：```
n = 3
w = [3, 2, 1]
1 - 2
2 - 3
```我们以 1 为根。父指针是 2 → 1、3 → 2。按权重排序的节点：1(3)、2(2)、3(1)。 

| 节点| 家长 | DSU 查找（父级）| 行动| 回答 |
 | ---| ---| ---| ---| ---|
 | 1 | - | - | 跳过| 0 |
 | 2 | 1 | 1 | 添加 2 | 2 |
 | 3 | 2 | 2 | 添加 1 | 3 |

 处理完 2 后，节点 3 仍然可以通过 2 或 1 向上连接，具体取决于 DSU 结构，总共为 3。 

这显示了树的多个级别如何顺序贡献为第二大元素。 

现在考虑一颗星：

 输入：```
1 is center with weight 100
others have weights 1, 2, 3
```排序后的订单根据重量在最后或第一个处理中心。 叶子附着到中心，但只有每个结构的第一个成功附着很重要。 该中心充当重复支撑，但每个叶子仅在与更高的节点配对时才作为第二大元素独立贡献，这表明贡献是由较高权重锚点的可用性驱动的。

    from sys import stdin

        g[v].append(u)

    order = []

        for v in g[u]:

            parent[v] = u
            stack.append(v)

            return self.p[x]

        if p == -1:
            continue
        v = dsu.find(p)
        if v != 0:
            ans += w[u]
            dsu.union(u, v)

    return str(ans)

 ## 边缘情况

 对于假设每个节点都必须向上附加的实现来说，单节点树是最简单的失败点。 在这种情况下，不存在大小至少为 2 的有效区域，因此答案必须为零。 该算法处理这个问题是因为根没有父节点并且被完全跳过。 

严格递增链测试 DSU 是否正确向上传播可用性。 在这样的链中，除了最大节点之外的每个节点都应该成功配对一次，并且该算法通过始终找到最近的更高祖先来实现这一点。 

星形树测试多个叶子是否错误地尝试以阻止以后配对的方式消耗中心。 由于 DSU 向上压缩，因此中心仍然是多个叶子的可重复使用的锚点，从而允许正确累积贡献。
