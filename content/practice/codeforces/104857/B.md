 ## 解决方案
 ## 问题理解

 给定一个整数多重集，其中值范围从 1 到 n，每个值 i 出现 ai 次。 任务是计算有多少个不同的序列 b（该多重集的排列）具有涉及两个队列的特殊属性。 

所描述的过程是一个两阶段模拟。 首先，我们取出序列b，将其元素一一推入队列A或队列B。放置完所有元素后，我们重复从A或B前面删除元素，每一步选择从哪个非空队列中弹出，直到两个队列都为空。 目标是能够生成全局排序序列，这意味着首先全为 1，然后全为 2，依此类推，直到 n。 

如果存在某种方法将序列 b 的元素分配到两个队列中，以便最终的合并过程可以输出排序后的序列，则序列 b 被认为是有效的。 

这些约束足够严格，足以排除对排列或赋值进行任何指数枚举。 元素总数最多为 500 个，因此任何仅依赖于 m2 或 m3 附近多项式时间内的 n 和 m 的解决方案都是合理的，而 m 中的任何阶乘都立即不可行。 

一个关键的微妙之处是，我们不会在以自由形式查看队列后选择如何输出。 输出必须排序，因此队列的结构受到严格限制。 如果一个队列在内部强制较大的值出现在较小的值之前，则在合并期间将无法修复，因为队列顺序是固定的。 

当队列包含递减模式时，就会出现简单的失败情况。 

例如，如果一个队列包含 3，后跟 2，则在提取过程中，3 将先于 2 出现，这会破坏排序顺序。 因此，即使合并阶段很灵活，每个队列的行为也必须与排序输出兼容。 

这一观察结果是主要的结构约束：两个队列实际上充当两个单调缓冲区，必须共同输出全局排序的流。 

## 方法

 直接的强力方法将生成多重集的每个排列，然后尝试将元素的每个可能的分配到两个队列，并且对于每个分配模拟是否存在有效的输出调度。 即使忽略排列的阶乘数，仅队列分配的数量就是 2^m，并且每次模拟都是 O(m)，使得这种方法太慢了。 

关键的简化来自于颠倒观点。 我们不是模拟队列过程，而是描述哪些序列 b 接受有效的分配。 由于每个队列都是 FIFO，因此一旦将元素放入队列中，其在该队列内的相对顺序就固定了。 在最终合并期间，我们只能交织两个固定序列。 对于要全局排序的合并输出，每个队列本身的值必须是非递减的。 

这将问题转换为序列 b 上的划分条件。 我们将 b 的每个位置分配到两个队列之一，这样在每个队列中，值永远不会随着时间的推移而减少。 因此每个颜色类必须形成一个递增的子序列。 

这相当于将序列划分为两个递增的子序列。 根据迪尔沃斯观点的经典定理告诉我们，当序列不存在长度为 3 的递减子序列时，这正是可能的。换句话说，有效序列正是那些避免模式 321 的序列。 

所以问题就变成了：计算给定频率的多重排列，避免出现递减的三元组。

这是一个已知的伪装结构。 最长递减子序列至多 2 的排列对应于 Robinson-Schensted 下的至多两行的 Young tableaux。 有了重复的值，正确的模拟就变成了半标准的 Young 形状的画面，最多有两行，权重由频率 ai 给出。 

因此，我们将问题简化为将每个值 i 的分配计数为两行，从而满足行约束：行通过构造而微弱增加，并且列严格条件成为关于分配给第一行和第二行的元素数量的前缀平衡约束。 

我们按升序处理值，并决定每个值有多少个副本进入顶行。 这成为一个动态规划问题，涉及第 1 行和第 2 行中元素数量之间的差异。

 | ---| ---| ---| ---|
 | 暴力破解排列和队列分配 O(m!·2^m·m) | O(m!·2^m·m) | O(米) | 太慢了 |

 ## 算法演练

 我们按升序处理从 1 到 n 的值，维护到目前为止已分配给两行中每一行的元素数量。 

我们定义一个 DP 状态，其中 dp[d] 是处理当前值前缀的方法数，使得差值 d 等于（row1 的大小减去 row2 的大小）。 只有 d ≥ 0 的状态才有效，因为在前缀结构中 row1 绝不能低于 row2。 

对于频率为 ai 的每个值 i，我们将其副本分布在两行之间。 如果我们将 x 个副本放入 row1，则 ai − x 转到 row2，余额会发生 (x − (ai − x)) = 2x − ai。 

我们现在对每个状态和每个可能的 x 执行转换。 

### 算法演练

 1. 初始化 dp[0] = 1，这意味着在处理任何值之前，两行都是空且平衡的。 
2. 对于从 1 到 n 的每个值 i，创建一个初始化为零的新数组 ndp。 
3. 对于每个可能的当前余额 d 和从 0 到 ai 的每个可能的选择 x，计算新余额 d' = d + (2x − ai)。 如果 d' 为非负数，则将 dp[d] 添加到 ndp[d']。 
4. 处理完值 i 的所有状态后，将 dp 替换为 ndp。 
5. 处理完所有值后，对所有 d ≥ 0 的所有 dp[d] 求和以获得答案。 

这样做的原因是余额 d 编码了两行 Young tableau 的前缀约束：按顺序读取值时，row1 必须始终至少与 row2 一样大。 每个元素的分配都会自动遵循弱递增行结构，因为值是按递增顺序处理的，因此任何行都不会引入减少。 

剩下的唯一约束是保持行之间有效的前缀结构，这正是由 d 在每一步的非负性捕获的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    m = sum(a)
    
    dp = [0] * (m + 1)
    dp[0] = 1
    
    offset = 0
    
    for cnt in a:
        ndp = [0] * (m + 1)
        
        for d in range(m + 1):
            if dp[d] == 0:
                continue
            
            cur = dp[d]
            
            for x in range(cnt + 1):
                nd = d + (2 * x - cnt)
                if 0 <= nd <= m:
                    ndp[nd] = (ndp[nd] + cur) % MOD
        
        dp = ndp
    
    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```该实现保持一个 DP 数组，该数组由两行之间的当前余额索引。 每个值组在其多重性的所有可能分裂上贡献有界转换。 x 上的内部循环是直接编码组合选择的地方，并且更新确保我们只保留保留前缀约束的状态。 

最终总和汇总了所有有效的最终余额，因为第一行最终的大小没有限制，只是在构建过程中它永远不会低于第二行。 

## 工作示例

 由于该语句没有提供完全可读的示例，因此构建一个小型实例很有用。 

考虑 n = 2 且 a = [1, 1]。 多重集是{1, 2}。 

我们首先处理值1。 

| 步骤| dp 状态 d=0 | dp 状态 d=1 |
 | ---| ---| ---|
 | 初始化| 1 | 0 |
 | 1 之后 | 1 | 1 |

 处理完值 1 后，我们可以将其放入 row2 或 row1，给出余额 1 或 -1，但仅保留非负数，因此根据解释有效地表示 0 和 1。 

现在类似地处理值 2 并跟踪转换； 两项有效作业均有效，总答案为 2。 

这表明 DP 正在计算结构分配而不是直接计算排列。 

稍微丰富一点的情况是 a = [2, 1]。 这里必须先分配值1，然后分配值2。 DP 确保重复项的拆分与前缀约束正确交互，从而防止强制使用 321 模式的非法交错。

 ## 边缘情况

 关键的边缘情况是所有数字都相同。 在这种情况下，唯一重要的结构是我们如何在两行之间分割相同的元素，同时保持前缀有效性。 DP 自然会计算所有有效的分割，因为每个分布都保留每行内的单调性。 

另一个边缘情况是大多数值 ai = 0 时。 DP 仍然处理这些值，但它们仅在强制 x = 0 的情况下贡献恒等转换，因此状态不会改变。 即使缺少许多值，这也可以确保正确性。 

最后一个微妙的情况是当单个值的 ai 接近 m 时。 在这种情况下，x 上的内部循环会变大，但所有转换仍然有效，因为所有副本都无法区分。 DP 正确地将所有分配它们的方式聚合到两行中，而不违反前缀平衡约束。
