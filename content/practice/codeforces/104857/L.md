 ## 解决方案
 ## 问题理解

 我们得到一个有向图，其中每个顶点代表一个学生，每个有向边代表信息从一个学生传递到另一个学生的可能方式。 每条边都带有一个概率（以分数形式给出），它模拟了信息在考虑时沿着该连接成功传播的机会。 

传播过程并不是简单的一次性传播。 相反，它遵循从学生 1 开始的深度优先遍历，并且在遍历期间严格按照输入顺序处理边。 当我们还是学生的时候`u`，我们检查传出边缘`u -> v`， 如果`u`已经知道信息但是`v`不，那么`v`以等于边权重的概率被通知。 之后，我们递归地继续DFS`v`无论传输是否成功。 

这创建了一个微妙的依赖结构：DFS 顺序是确定性的，但概率状态影响未来的可达性。 一名学生可能会在 DFS 中被多次拜访，但只有第一次拜访才重要，因为`visited`大批。 

任务是计算每个学生最终被标记为的概率`aware`整个随机 DFS 过程完成后。 

约束条件达到`n = 100000`和`m = 300000`，这立即排除了任何显式模拟概率过程或枚举边子集的方法。 即使存储状态的中间概率分布也会呈指数爆炸。 我们必须将过程压缩为对图的单次传递，理想情况下是线性或接近线性的`n + m`。 

当循环存在时，就会出现一个微妙的问题。 由于 DFS 可以在完成较早的分支之前通过递归重新访问节点，因此每条边的朴素概率传播很容易重复计算路径或错误地假设独立性。 另一个棘手的情况是边的顺序很重要，因此将图视为无序概率网络是不正确的。 

例如，考虑一个循环`1 -> 2 -> 3 -> 1`其中每条边的概率为 1。一个简单的“可达性概率”DP 可能会尝试对到一个节点的多条路径求和，但实际上，DFS 访问结构将其折叠为确定性树遍历，使每个节点按 DFS 顺序有效进入一次。 

另一种边缘情况是来自节点的多个传出边缘竞争时。 如果`u`有两个出边`v1`和`v2`，到达每个的概率在通常意义上不是独立的，因为两者都以 DFS 到达为条件`u`以及探索的顺序。 

核心难点在于，这个过程不仅仅是图上的概率可达性，而是沿着具有确定性结构的 DFS 树的概率激活。 

## 方法

 强力解释将模拟 DFS 过程并在每个概率决策上明确分支。 每次边遍历都会引入一个二进制随机结果，因此可能世界的数量会随着边的数量呈指数增长，即使对于小图来说也是不可行的。 由于精度要求，即使是蒙特卡罗模拟也是不可靠的。 

关键的观察是，虽然过程是随机的，但 DFS 遍历的结构是确定性的。 唯一的随机性来自节点是否被标记`aware`此刻，我们检查了一个已经意识到的父母通向它的边缘。 一旦节点意识到，它就会永远保持感知，并且 DFS 结构确保首先沿着唯一的 DFS 路径发现每个节点。 

这建议将问题重新定义为每个节点的计算`v`，DFS第一次到达时成功激活的概率。 该概率取决于 DFS 树中的父级以及用于到达它的边。 

我们没有考虑原始图中的多条路径，而是将遍历顺序产生的 DFS 树视为固定的，并计算沿树边缘的转移概率。 每个节点聚合来自其 DFS 父节点的贡献，并且多个传出边的影响通过在继续遍历之前不激活任何子节点的概率失败的线性来处理。 

一个重要的见解是，对于每个节点，我们可以维持 DFS 在其仍处于非活动状态时到达该节点的概率，然后将其转换为激活概率。 这使我们能够执行单个 DFS，同时保持按输入顺序沿边缘正确的概率传播。 

最终的解决方案成为一个 DFS，它仔细维护了到达每个节点并按顺序更新子状态的概率。

 ## 算法演练

 我们将 DFS 解释为一种遍历，为每个节点分配一个“到达概率”，即我们到达该节点且处于尚未感知且可以激活的状态的概率。 

我们维护一个概率数组`dp[v]`表示DFS到达节点的概率`v`在一个状态下`v`尚未激活。 我们还维护`ans[v]`，最终的概率`v`变得意识到。 

### 步骤

 1. 从节点 1 开始，具有`dp[1] = 1`，因为 DFS 从那里开始，并且它最初根据定义是已知的。 我们设定`ans[1] = 1`立即，因为它是按照最初通知的方式给出的。 
2. 从节点 1 运行 DFS。在节点的 DFS 期间`u`，我们按照输入顺序处理传出边，因为该过程明确依赖于该顺序。 
3. 对于每个出边`u -> v`有概率`p/q`，考虑两个互补事件：`v`当这条边被处理时，它已经知道，或者仍然不知道。 价值`dp[u]`代表我们到达的概率`u`同时它仍然没有被沿其传入 DFS 路径的早期成功激活“消耗”。 
4、加工边缘时`u -> v`，这条边引起的概率`v`意识到是`dp[u] * w`， 在哪里`w = p * q^{-1}`模 MOD。 这是因为我们首先必须处于`u`处于未消费状态，则激活成功。 
5. 我们将其累积为`ans[v]`，因为多条边最终可能会尝试激活`v`，但我们必须在模算术中正确组合独立成功的首次激活的概率。
 6. 尝试通过边缘激活后，我们继续 DFS 进入`v`。 然而，DFS 进入`v`只有我们在结构上达到目标才重要； 它的 dp 状态表示即使没有发生激活，我们也已到达。 
7. 继续递归，向前传播到达概率。 

### 为什么它有效

 不变量是当DFS进入一个节点时`u`，值`dp[u]`正好表示遍历到达的概率`u`没有`u`已经被 DFS 顺序中任何先前的边激活。 每一条边出`u`然后独立地影响以该到达事件为条件激活其目标的概率。 因为 DFS 确保每个节点都以固定的结构顺序进入，并且激活是单调的（一旦感知，始终感知），因此我们绝不会以违反概率空间划分的方式重复计算节点的成功激活事件。 来自不同边缘的贡献对应于不相交的首次成功场景，从而保持了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def main():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v, p, q = map(int, input().split())
        w = p * modinv(q) % MOD
        g[u].append((v, w))
    
    sys.setrecursionlimit(10**7)
    
    dp = [0] * (n + 1)
    ans = [0] * (n + 1)
    vis = [False] * (n + 1)
    
    dp[1] = 1
    ans[1] = 1
    
    def dfs(u):
        vis[u] = True
        for v, w in g[u]:
            if not vis[v]:
                ans[v] = (ans[v] + dp[u] * w) % MOD
                dp[v] = (dp[v] + dp[u] * w) % MOD
                dfs(v)
    
    dfs(1)
    
    for i in range(1, n + 1):
        print(ans[i] % MOD)

if __name__ == "__main__":
    main()
```邻接列表保留输入顺序，这很重要，因为边缘处理顺序会影响首先发生的激活尝试。 DFS 使用访问数组来确保每个节点在结构上处理一次，与伪代码的匹配`visited`约束。 

模逆将有理概率转换为模算术`998244353`。 每个传播步骤将父到达概率乘以边缘概率，反映条件激活。 

数组`dp`和`ans`将结构范围与累积激活概率分开。 这种分离可以防止将“在 DFS 中到达”与“被激活”混合在一起，而“在 DFS 中到达”和“被激活”是过程中不同的事件。

 ## 边缘情况

 一种重要的边缘情况是节点具有按 DFS 顺序排列的多个传入边缘。 该算法通过将贡献累积到`ans[v]`而不是覆盖它。 例如，如果节点`v`可以从两者激活`u1`和`u2`，每条路径通过独立贡献`dp[u1] * w1`和`dp[u2] * w2`，并且两者都被添加。 由于这些对应于以不同遍历状态为条件的不相交 DFS 激活尝试，因此加法是正确的。 

另一种情况是当图形包含循环时。 因为`visited`数组，DFS在结构上确保每个节点只扩展一次。 即使存在循环，我们也不会重新进入节点，防止无限递归，也防止重复的概率放大。 这与伪代码行为相匹配，其中`visited`块再处理。 

最后一个微妙的情况是当一条边的概率为 0 或 1 时。如果它是 0，则它对`ans`，而DFS在结构上仍然延续。 如果为 1，则激活是确定性的，并且传播只是完全传输`dp[u]`将质量传递给孩子，无需任何特殊处理即可保持正确性。
