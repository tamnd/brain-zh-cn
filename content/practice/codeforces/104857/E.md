 ## 解决方案
 ## 问题理解

 我们被赋予了一个$n \times m$网格，其中每个单元格包含一个整数颜色。 对于每种颜色，我们都会查看具有该颜色的所有单元格，并考虑此类单元格的每个有序对。 对于每一对，我们计算它们坐标之间的曼哈顿距离，并将所有颜色的所有这些距离相加。 

因此，任务不是关于任意单元格之间的距离，而是严格限制在每个颜色组内。 每种颜色在网格上形成一组点，我们需要每个组内的总成对曼哈顿距离，并对所有组求和。 

限制因素$n, m \le 1000$暗示直到$10^6$细胞。 每种颜色的简单二次方法显然会失败，因为在最坏的情况下，所有单元共享相同的颜色，产生$10^{12}$对。 即使对所有对进行线性扫描也是不可能的。 

一个微妙的点是该问题计算有序对$(i, j)$，而不仅仅是无序对。 与独特的配对相比，这使得贡献增加了一倍。 简单的解决方案可能会计算无序距离并忘记乘以 2，从而导致错误的结果。 

重要的边缘情况包括：

 所有单元格都具有相同颜色的网格。 例如：```
2 2
1 1
1 1
```正确答案是 8，因为每个无序对贡献两次。 

另一种情况是所有颜色都是唯一的：```
2 2
1 2
3 4
```答案是 0，因为没有一种颜色具有多个单元格。 如果不仔细处理组，尝试计算成对差异而不检查组大小的幼稚实现可能仍然会尝试不必要的工作，甚至会产生索引错误。 

## 方法

 强力解决方案修复每种颜色，收集其所有坐标，并计算每个有序对之间的距离。 如果出现颜色$k$次，这需要花费$O(k^2)$。 对所有颜色求和，这会退化为$O(n^2 m^2)$在最坏的情况下，因为一种颜色可能占据整个网格。 

关键的观察结果是曼哈顿距离干净地分成行坐标和列坐标的独立贡献。 对于两点$(x_1, y_1)$和$(x_2, y_2)$,$$|x_1 - x_2| + |y_1 - y_2|$$可以被处理为纯基于 x 的项和纯基于 y 的项之和。 

这意味着我们可以独立于 y 坐标来处理颜色的所有 x 坐标。 总贡献变为：

 对（成对 |x_i - x_j| 的总和 + 成对 |y_i - y_j| 的总和）的颜色求和。 

现在，问题简化为计算每个颜色组的一维数组中的绝对差之和，两次：一次针对行，一次针对列。 

对于一维序列，排序值允许我们使用前缀累加来计算线性时间中成对绝对差的总和。 我们不是比较所有对，而是维护一个运行的前缀和并在扫描时累积贡献。 

这会在排序后将每个颜色组从二次减少为线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O((nm)^2)$|$O(nm)$| 太慢了 |
 | 最佳|$O(nm \log nm)$|$O(nm)$| 已接受 |

 ## 算法演练

 ### 1. 按颜色对单元格进行分组

 我们扫描网格一次并为每种颜色存储两个列表：其行索引和列索引。 这种分离是必要的，因为曼哈顿距离分为独立的 x 和 y 贡献。 

### 2. 对于每种颜色，处理行坐标

 我们对该颜色的行索引列表进行排序。 需要排序，以便可以用结构化前缀和而不是成对比较来代替绝对差异。 

### 3. 计算行的贡献

 我们在排序的行上维护一个运行前缀和。 处理一个值时$x_i$，所有先前的值$x_j$贡献$x_i - x_j$，所有未来的贡献将在稍后进行反向累加处理。 这将成对差异转换为线性更新。 

### 4. 对列坐标重复

 我们对列索引应用相同的过程。 这独立地解释了曼哈顿距离的垂直分量。 

### 5. 对所有颜色的贡献求和

 每种颜色独立贡献，因此我们累积所有组的结果。 

### 为什么它有效

 对于任何固定颜色，我们正在计算：$$\sum |x_i - x_j| + \sum |y_i - y_j|$$求和的线性允许分割坐标。 排序前缀方法确保每对都以正确的大小精确计数一次，因为每个元素按排序顺序按比例影响其前后的元素数量。 颜色之间不存在相互作用，因此独立处理它们可以保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def sum_abs_pairs(arr):
    arr.sort()
    res = 0
    prefix = 0
    for i, x in enumerate(arr):
        res += x * i - prefix
        prefix += x
    return res

def solve():
    n, m = map(int, input().split())
    rows = defaultdict(list)
    cols = defaultdict(list)

    for i in range(n):
        line = list(map(int, input().split()))
        for j, c in enumerate(line):
            rows[c].append(i)
            cols[c].append(j)

    ans = 0
    for c in rows:
        ans += sum_abs_pairs(rows[c])
        ans += sum_abs_pairs(cols[c])

    print(ans)

if __name__ == "__main__":
    solve()
```该实现维护两个按颜色键控的哈希图。 每种颜色分别累积行和列位置，这对于保留曼哈顿距离的分解至关重要。 

功能`sum_abs_pairs`是核心优化。 排序后，它使用固定元素的标识$x_i$，所有先前的元素总共贡献$x_i \cdot i - \text{prefix sum}$。 这避免了显式的对枚举。 

一个常见的错误是迭代无序列表。 如果不排序，前缀减法并不对应绝对差，结果就会变得不正确。

 ## 边缘情况

 密集的单色网格是最敏感的情况。 例如：```
2 2
1 1
1 1
```该算法存储行`[0,0,1,1]`和列`[0,1,0,1]`对于那种颜色。 排序后，两者都变成`[0,0,1,1]`。 行贡献为$(1-0) + (1-0) + (1-0) + (1-0) = 4$，并且列贡献相同，总共 8。 前缀和方法确保每对在每个方向上精确计数一次，并且排序对称性会产生正确的双倍贡献。 

第二个边缘情况是许多单一颜色。 每个列表的大小为 1，因此排序后，前缀逻辑贡献为零，因为不存在对。 该算法自然会跳过不必要的工作，因为行和列贡献都保持为零。
