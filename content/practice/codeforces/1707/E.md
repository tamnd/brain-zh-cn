 ## 解决方案
 ## 问题理解

 我们得到一个整数数组`a`长度`n`，其中每个元素介于 1 和`n`。 从概念上讲，将它们想象为排成一排的带标签的图块。 我们在连续段上定义“替换”操作`(l, r)`：它将段折叠成对`(min value in the segment, max value in the segment)`。 我们可以重复应用这个操作：每一步都映射当前的`(l, r)`到该范围定义的子数组的最小值-最大值。 

查询询问：从给定的开始`(l, r)`，我们需要达到多少替代品`(1, n)`？ 如果不可能——也就是说，替换序列进入一个永远不会覆盖完整的循环`[1, n]`- 我们回来`-1`。 

约束告诉我们`n`和`q`每个最多可以达到 100,000，因此每个查询中对子数组的简单迭代太慢了。 如果我们考虑一个简单的解决方案，通过在每次替换时扫描子数组来重新计算最小值和最大值，那么最坏情况的操作计数大约是`O(n * q)`如果每个查询需要多次替换，则甚至更高。 这将达到`10^10`操作，远远超出了2秒的时间限制。 我们需要一种更智能的方法来减少重复扫描。 

一个微妙的边缘情况是无限循环更换。 例如，数组`[2, 1]`带查询`(1, 1)`产生`(2, 2) → (1, 1) → (2, 2)`永远。 一个粗心的解决方案，假设最终收敛到`(1, n)`将错误地返回一个数字而不是`-1`。 当起始段已经存在时，会发生另一种边缘情况`(1, n)`; 答案应该是`0`。 

## 方法

 蛮力方法很简单。 对于每个查询`(l, r)`，重复计算最小值和最大值`a[l..r]`直到达到`(1, n)`或检测到循环。 这是正确的，因为它模拟了所描述的确切过程，但速度太慢。 步骤数可以是`O(n)`每个查询，并且天真地计算最小值和最大值也是`O(n)`，产生`O(n^2 * q)`运营。 为了`n, q = 10^5`，这显然是不可行的。 

关键的观察是替换操作只会扩展段：最小值只能减少或保持不变，而最大值只能增加或保持不变。 这种单调性质表明该过程可以提前预测。 我们可以将数组预处理成一个结构，允许我们从一个跳转`(l, r)`到下一个`(l', r')`在`O(1)`或者`O(log n)`时间。 具体来说，我们注意到对于任何`x`在`[1, n]`，第一次和最后一次出现的`x`定义一个段，如果我们想要到达，最终必须覆盖该段`(1, n)`。 通过重复合并与连续数字相对应的重叠段，我们可以计算替换的最小数量，而无需为每个查询扫描数组。 

由此产生的方法是区间扩展和二元提升的组合。 首先，为每个位置预处理一次替换中可以达到的最大间隔。 然后，对于每个查询，使用加倍表重复应用跳转以达到`(1, n)`高效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2 * q) | O(n^2 * q) | O(1) | O(1) | 太慢了|
 | 最优（间隔合并+加倍）| O(n log n + q log n) | O(n log n + q log n) | O(n log n) | O(n log n) | 已接受 |

 ## 算法演练

 1. 预先计算每个值的第一次和最后一次出现`1`到`n`。 让`first[x]`和`last[x]`表示第一个和最后一个索引，其中`a[i] = x`。 这让我们知道覆盖所有出现的值的最小段。 
2. 计算初始展开`b[i]`对于每个索引`i`。`b[i]`是从以下位置可以到达的最右边的索引`[i, i]`一次更换。 初始化`b[i] = i`。 迭代值`1..n`按顺序，并对每个值展开`b[i]`为所有人`i`在其段中覆盖最小-最大间隔。 这一步之后，`b[i]`表示一步中可到达的最大段`[i, i]`。 
3. Build a doubling table. 让`jump[k][i]`是可到达的最远右侧索引`i`使用`2^k`替代品。 使用递归填充此表`jump[k][i] = jump[k-1][jump[k-1][i]]`。 This allows us to answer queries in`O(log n)`通过二的跳跃幂。 
4. 对于每个查询`(l, r)`，首先检查是否`(l, r)`已经涵盖了`(1, n)`。 如果是，则返回`0`。 否则，展开`(l, r)`使用倍增表：从2的最高次幂开始，只要不超过就跳转`n`。 如果我们最终跳跃到`n`并覆盖`1`左侧，返回跳跃次数。 否则，返回`-1`。 

为什么它有效：倍增表确保我们永远不会重复重新计算同一段的最小值/最大值。 预先计算的最大范围恰好捕获一个替换操作。 段扩展的单调性保证了重复应用永远不会缩小间隔，因此该过程不会错过最小步数。 循环被隐式处理：如果我们无法到达`(1, n)`，跳转表最终将无法扩展该段，从而产生`-1`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    first = [n] * (n + 1)
    last = [-1] * (n + 1)
    for i, val in enumerate(a):
        first[val] = min(first[val], i)
        last[val] = max(last[val], i)
    
    b = list(range(n))
    i = 0
    while i < n:
        r = i
        j = i
        while j <= r:
            val = a[j]
            r = max(r, last[val])
            j += 1
        for k in range(i, r + 1):
            b[k] = r
        i = r + 1

    LOG = 20
    jump = [b]
    for k in range(1, LOG):
        nxt = [0] * n
        for i in range(n):
            nxt[i] = jump[k-1][jump[k-1][i]]
        jump.append(nxt)

    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1
        if l == 0 and r == n - 1:
            print(0)
            continue
        if b[l] < r:
            print(-1)
            continue
        ans = 0
        cur_l = l
        cur_r = r
        for k in reversed(range(LOG)):
            nxt_r = jump[k][cur_l]
            if nxt_r < n - 1:
                cur_l = nxt_r + 1
                ans += 1 << k
        if cur_l <= 0 and jump[0][cur_l] >= n - 1:
            ans += 1
            print(ans)
        else:
            print(-1)

if __name__ == "__main__":
    solve()
```第一部分计算第一次和最后一次出现的情况。 第二个计算`b[i]`使用段扩展。 然后我们准备快速跳跃的加倍表。 在查询中，我们检查初始覆盖率、无效段，然后重复跳转。 差一错误非常重要：对于 Python 列表，索引将转换为基于 0 的索引，并且扩展中必须包含段边界。
