 ## 解决方案
 ## 问题理解

 我们有一系列的比赛，每场比赛都与特定的一天相关，并且每场比赛都有一个难度级别。 Doremy 从初始智商开始`q`，代表她处理比赛的能力。 每天，她都可以选择参加比赛或跳过比赛。 如果她尝试参加一场比赛，并且难度大于她当前的智商，她的智商就会降低一。 否则，它保持不变。 如果她的智商为零，她就不能参加比赛。 

输入提供多个测试用例。 每个测试用例指定了比赛次数、Doremy 的起始智商以及比赛难度列表。 输出必须是一个二进制字符串，表示 Doremy 应该尝试在哪些比赛中最大化她可以测试的总数，而不让她的 IQ 降至零以下。 

约束意味着我们必须处理最多`10^5`所有测试用例的总竞争。 每个测试用例 O(n log n) 的算法是可以接受的，但 O(n^2) 就太慢了。 由于智商可以高达`10^9`，我们无法显式模拟每个可能的 IQ 值。 

不明显的边缘情况包括一些较困难的比赛出现在较容易的比赛之前的序列。 例如，如果`q=2`比赛是`[5,1,1]`，一种从左到右贪婪地尝试比赛的幼稚方法可能会选择`5`首先，将 IQ 降低至`1`，然后选择`1`和`1`，这很好。 但如果`q=1`比赛是`[2,1,1]`，选择第一个比赛会将 IQ 降低到`0`，防止测试后续更简单的比赛。 这表明我们可以安全地尝试任何难度低于以下的比赛`q`最后，或者策略性地推迟困难的比赛，直到智商下降到某个阈值。 

## 方法

 暴力方法模拟了 Doremy 日复一日的选择。 对于每场比赛，检查 IQ 是否大于零。 如果是这样，请测试比赛，如果其难度超过当前的 IQ，则降低 IQ。 否则，跳过。 每个测试用例的时间复杂度为 O(n)，并且考虑到约束，它实际上是可以接受的。 这种幼稚的方法是正确的，因为按顺序测试竞赛尊重“日”限制。 只有当我们试图以贪婪的方式最大化测试而不正确跟踪智商时，它才会失败。 

最佳方法的关键洞察是认识到唯一威胁智商的比赛是那些难度超过起始智商的比赛。 任何难度小于或等于`q`总是可以被测试的。 对于难度高于`q`，多蕾米只有在智商仍然为正的情况下才能测试他们。 由于当一场比赛太难时，智商会下降一分，所以我们可以考虑一个阈值：一旦智商达到剩余比赛都小于或等于阈值的水平，我们就可以安全地尝试所有比赛。 

因此，我们可以从末尾向后迭代。 对于每场比赛，如果其难度小于或等于当前 IQ，则将其标记为可测试。 否则，如果 IQ 为正，则将其标记为可测试并减少 IQ。 如果 IQ 为零，则将其标记为不可测试。 向后迭代可确保我们不会过早地将智商浪费在简单的比赛上，从而使我们能够最大限度地增加测试的比赛数量。

 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 已接受 |
 | 最优（后向贪婪）| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，请阅读`n`和`q`，以及一系列的比赛难点`a`。 
3.初始化答案数组`ans`长度`n`全为零。 
4. 以相反的顺序迭代比赛（从最后一天到第一天）：

 1.如果比赛难度`a[i]`小于或等于当前IQ`q`， 放`ans[i] = 1`。 
2. 否则，如果智商`q`为正，设`ans[i] = 1`并将 IQ 减一。 
3.否则，离开`ans[i] = 0`。 
5.处理完所有竞赛后，输出对应的二进制字符串`ans`。 

为什么它有效：该算法在每个位置都保持不变`i`，在左边的比赛中剩余智商最大化。 通过向后迭代，我们优先测试那些在 IQ 耗尽时我们会跳过的比赛，确保困难的比赛不会不必要地阻碍较容易的比赛。 这保证了测试最大数量的竞赛。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        ans = [0] * n
        for i in reversed(range(n)):
            if a[i] <= q:
                ans[i] = 1
            elif q > 0:
                ans[i] = 1
                q -= 1
        print("".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```该解决方案首先使用快速 I/O 读取输入。 它构建答案数组并从头到尾填充它，检查比赛是否在 IQ 范围内，或者测试它是否会降低 IQ。 向后迭代对于最大化比赛数量至关重要。 边缘条件（例如 IQ 为零）自然由条件检查处理。
