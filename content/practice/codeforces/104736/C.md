 ## 解决方案
 ## 问题理解

 我们得到了一排糖果，每个糖果都贴有品牌 ID。 我们可以选择这条线的一个连续的段并购买该段中的所有糖果。 

家庭成员恰好有 K 名，每位成员必须收到恰好一个品牌的糖果。 两个会员之间不能共享任何品牌，并且每个会员必须获得相同数量的糖果。 这意味着，在购买了一个细分市场后，我们必须能够将该细分市场中的糖果分成K组，每个家庭成员一个，其中每个组仅包含一个品牌，并且所有组的大小相同。 

用数组术语重新表述，我们正在寻找一个子数组，在该子数组中我们可以精确地选取 K 个不同的值，并且每个值在子数组中出现的次数相同。 如果该公共频率为 f，则子数组长度为 K·f，并且子数组内的每个元素都必须属于这 K 个选定值。 

任务是最大化这样一个子数组的长度。 

限制最多允许 4·10^5 颗糖果。 任何 N 的二次解都会立即失败，因为在最坏的情况下它会执行 10^10 次运算。 即使 N log N 方法也是可以接受的，但前提是它们保持紧密的线性扫描或有效的窗口维护。 该结构强烈建议采用滑动窗口或两指针策略。 

当根本无法满足条件时，就会出现微妙的边缘情况。 例如，如果 K = 4，但数组全局仅包含三个不同的品牌，则任何子数组都不能包含频率相同的四个不同的品牌，因此答案必须为零。 

当子数组包含 K 个不同的品牌但它们的出现频率仅相差一次时，就会出现另一种失败情况。 例如，K = 2 且子数组`[1, 1, 2]`计数为 2 和 1，这违反了平等性，即使两个品牌都存在。 

## 方法

 蛮力策略很简单：枚举每个子数组，计算其中每个品牌的频率，然后检查是否正好出现 K 个品牌，并且所有品牌都有相同的计数。 维护每个子阵列的频率图可以为每个起始位置提供 O(N) 工作量，从而导致总时间为 O(N^2)。 当 N 达到 4·10^5 时，这变得太慢了。 

关键的观察结果是，我们实际上并不关心品牌的身份，只关心窗口内的频率结构。 有效窗口的完全特征是所有存在的频率都相等，并且恰好有 K 个不同的值。 

这建议维护一个具有频率计数的滑动窗口，同时还跟踪当前有多少个值具有每个频率。 如果在任何点，所有 K 个不同元素共享相同的频率 f，则窗口有效，其长度为 K·f。 

困难在于，当我们扩大或缩小窗口时，频率会动态变化。 我们不是从头开始检查相等性，而是维护一个二级结构，将频率值映射到当前有多少个元素具有该频率。 当该辅助映射的大小为 1 并且计数等于 K 时，窗口恰好有效。 

这减少了维护动态窗口的问题，每步的摊销更新为 O(1)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(N²) | O(N) | 太慢了|
 | 具有频率簿记功能的滑动窗口| O(N) | O(N) | 已接受 |

 ## 算法演练

 我们维护一个滑动窗口`[l, r]`，一本字典`freq`存储每个品牌的数量和字典`freq_count`存储当前有多少个品牌具有给定频率。 

1. 初始化`l = 0`,`freq = empty`,`freq_count = empty`， 和`answer = 0`。 
2. 将窗口右端一次展开一个元素。 对于位置上的每个新糖果`r`，更新其频率`freq`。 如果之前的频率为a，则递减`freq_count[a]`，如果新频率变为 b，则递增`freq_count[b]`。 

这保持`freq_count`与当前窗口一致，无需从头开始重新计算。 
3. 每次展开后，窗口可能会违反约束。 当窗口无效时，我们从左侧缩小。 仅当一个窗口恰好包含 K 个不同的品牌并且所有品牌共享相同的频率时，该窗口才有效。 按照`freq_count`，这意味着它必须恰好包含一个频率值，并且该值必须恰好出现 K 次。 
4.收缩时，我们移除`s[l]`从窗口中更新其频率`freq`，并调整`freq_count`相似地。 然后我们增加`l`。 

收缩是必要的，因为一旦品牌的频率变得不一致，如果不首先消除冲突的结构，仅靠未来的扩张就无法恢复统一。 
5. 恢复有效性后，计算窗口长度并更新答案。 
6. 继续，直到右指针到达末尾。 

### 为什么它有效

 在每一步中，窗口都是以以下结尾的最小前缀`r`这可能会满足约束条件。 的维护`freq_count`确保在频率均匀性破坏时立即检测到任何违规行为。 由于每个有效窗口在扩展后变得有效时都会被准确地考虑`r`，没有候选人被跳过。 滑动窗口不变量是`freq_count`始终准确地表示当前窗口的频率分布，因此有效性检查是精确的而不是启发式的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    freq = {}
    freq_count = {}
    
    l = 0
    ans = 0

    def add(x):
        old = freq.get(x, 0)
        if old > 0:
            freq_count[old] -= 1
            if freq_count[old] == 0:
                del freq_count[old]

        freq[x] = old + 1
        new = old + 1
        freq_count[new] = freq_count.get(new, 0) + 1

    def remove(x):
        old = freq[x]
        freq_count[old] -= 1
        if freq_count[old] == 0:
            del freq_count[old]

        if old == 1:
            del freq[x]
        else:
            freq[x] = old - 1
            freq_count[old - 1] = freq_count.get(old - 1, 0) + 1

    for r in range(n):
        add(a[r])

        while True:
            if len(freq) != k:
                break
            if len(freq_count) != 1:
                remove(a[l])
                l += 1
                continue

            f = next(iter(freq_count))
            if freq_count[f] != k:
                remove(a[l])
                l += 1
                continue

            break

        if len(freq) == k and len(freq_count) == 1:
            f = next(iter(freq_count))
            ans = max(ans, k * f)

    print(ans)

if __name__ == "__main__":
    solve()
```该代码维护两个同步的哈希映射。`freq`跟踪窗口内每个品牌的数量，同时`freq_count`跟踪有多少品牌共享每个频率。 仅当窗口违反非重复计数条件或等频条件时，内部循环才会收缩。 

一个常见的陷阱是当频率条目的计数降至零时忘记删除它们，这会错误地保留无效状态`freq_count`。 另一个微妙之处是，只有在更新完全应用于当前右端点后才会检查有效性。

 ## 边缘情况

 像这样的最小情况`K = 1`对于任何单元素窗口始终有效，因为每个细分在一个品牌中的频率通常相同。 该算法自然地处理这个问题，因为`freq_count`变成`{f:1}`，立即满足有效性条件。 

当数组全局包含少于 K 个不同值时，每个窗口都会失败`len(freq) == K`条件，因此任何收缩或检查都不能产生有效的状态。 答案正确地保持为零。 

如果存在有效配置但仅位于数组的最末尾，例如`1 1 2 2`，滑动窗口逐渐扩大，直到两个频率对齐，然后才触发有效性条件，确保不会错过晚出现的解决方案。
