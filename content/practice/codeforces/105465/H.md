 ## 解决方案
 ## 问题理解

 我们得到一排代表塔的位置，对于每个位置，我们被告知该塔必须能够“看到”或与多少个其他塔进行通信。 

如果两个塔之间不存在严格高于两个端点的塔，则它们可以进行通信。 换句话说，当您查看它们之间的部分时，只有当某个中间塔比它们都高时，通信才会被阻止。 如果至少一个端点比其间的所有端点都高，则该端点对已连接。 

任务不是计算这些关系，而是构建塔高度的分配，以便每个位置最终都有所需数量的可见塔。 

输出是一系列高度，每个高度在 1 到 10^9 之间。 可能存在多种解决方案，任何有效的解决方案都是可以接受的。 

约束最多为 5 · 10^5 塔，因此任何解决方案都必须本质上是线性或接近线性的。 任何涉及显式检查所有对或维护所有成对可见性的操作都会立即超出限制，因为这意味着在最坏情况下会出现二次行为。 

一个微妙的困难是可见性不是以简单的方式局部的。 更改单个高度可以改变长距离通信，因为它会影响它是否成为内部段的最大阻塞。 

一种常见的故障模式是将问题视为每个塔的度数仅取决于相邻结构或最近的较大元素。 例如，假设单调堆栈直接对答案进行编码是行不通的，因为可见性取决于端点之间的全局最大值，而不仅仅是下一个更大的关系。 

另一个陷阱是天真的假设该图是类似区间的。 一座塔可以根据高度的分布方式连接多个独立的区域，因此不控制全局分段的贪婪局部分配往往会破坏一致性。 

## 方法

 直接的强力方法会尝试分配高度，然后计算每对塔的可见性计数。 这需要检查所有对 i 和 j 并扫描它们之间的间隔以找到最大值，即每对 O(n)。 如果简单地完成，那么总共会导致 O(n^3)，或者如果对间隔最大值进行预处理，则最多会导致 O(n^2)。 即使 O(n^2) 也远远超出了 n 高达 5·10^5 的限制。 

关键的结构观察是可见性由段内的最大值决定。 这意味着，一旦我们确定了哪些塔楼充当“主要阻挡者”的概念，阵列就会自然地划分为这些阻挡者定义独立行为的区域。 

考虑最终配置的一个有用方法是使用较高高度的塔作为分离器。 位于由较高塔分隔开的不同区域的任何两个塔，如果该分隔器高于两个端点，则无法“透视”该分隔器。 因此，更高的塔将线路分割成独立的部分。 

现在考虑从最强的塔向下构建配置。 如果我们按降序分配高度，那么在放置新塔时，所有已放置的塔都会严格更高，并充当永久分离器。 剩余的未放置位置表现为尚未创建结构的较低元素的连续池。 

任何时候，放置的更高的塔都会将防线分成几段。 在每个部分内，所有剩余的塔目前都是等效的占位符，稍后将获得较低的高度。 关键的属性是，一旦将一座塔放入某个段中，其未来的可见性计数将恰好等于该段的大小减一，因为该段内的所有塔最终都将低于由更高元素创建的边界。

这减少了控制段大小的问题。 每个具有 a_i 要求的塔最终必须位于恰好包含 a_i + 1 个位置的段内，因为在这样的段内，它将连接到该段中的所有其他 a_i 位置，并且不会以增加额外可见性的方式连接到该段之外的任何位置。 

因此，构建过程变成了重复选择适当大小的空闲段并为其分配塔的过程，通过将其拆分到放置的塔周围来从未来的可用性中删除该段。 

使这一点保持一致的贪婪顺序是以递减的 a_i 处理塔，因为较大的可见性要求对应于必须作为更强的分离器更早放置的塔。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力可见性计算 | O(n^2) 到 O(n^3) | O(n) | 太慢了 |
 | 基于段的建设性布局 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将当前可用位置集维护为连续的空闲段。 每个段都有一个长度，我们需要能够快速定位到长度符合要求的段。 

我们还按照所需可见度的降序分配塔。 

1. 将所有索引按a_i降序排序。 我们将从那些能见度最大的塔开始放置塔。 
2. 将当前可用空间维护为段结构。 最初，有一个长度为 n 的线段。 
3. 对于按排序顺序的每个塔，取其要求 k = a_i。 我们需要一段长度为 k + 1 的空闲位置。 
4. 找到长度恰好为 k + 1 的任何线段。如果存在多个，则任何选择都是有效的，因为问题保证了可解性。 
5. 在该段内，将当前塔放置在任意位置，通常是最左边或中间位置。 这种布局将该段分成两个较小的段，这两个段仍可供以后的塔使用。 
6. 为该塔指定一个等于其处理顺序的高度，为较早处理的塔提供更高的值，以便它们充当后续步骤的分隔符。 

这样做的原因是，当将一座塔放置到大小为 k + 1 的段中时，最终位于该段中的所有剩余塔的高度都会较低。 同一最终段内的任何两个塔将具有由段边界控制的所有中间最大值，确保所放置塔的恰好 k 个可见连接。 

### 为什么它有效

 该结构确保在每一步中，已放置的塔都严格高于未放置的塔，因此它们永久地定义了未来塔在可见性扩展方面无法跨越的段边界。 每个新放置的塔完全占据了一个部分，其尺寸与其所需的能见度及其自身相匹配。 由于该段内不存在更高的塔，并且该段内的所有未来塔都较低，因此从该塔的角度来看，该段中的所有其他塔都只能看到一次，并且在该段外部不会产生额外的可见性，因为较高的分隔器会阻止任何违反要求的外部连接。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    order = sorted(range(n), key=lambda i: -a[i])

    segs = [(0, n)]  # intervals [l, r)
    res = [0] * n
    cur_height = n

    def find_segment(k):
        for i, (l, r) in enumerate(segs):
            if r - l == k:
                return i
        return -1

    for i in order:
        k = a[i] + 1
        idx = find_segment(k)

        l, r = segs.pop(idx)
        mid = l  # place at leftmost

        res[i] = cur_height
        cur_height -= 1

        if mid - l > 0:
            segs.append((l, mid))
        if r - (mid + 1) > 0:
            segs.append((mid + 1, r))

    print(*res)

if __name__ == "__main__":
    solve()
```代码首先通过降低需求来对塔进行排序，以便更早地解决更强的约束。 它维护一个空闲段列表，并重复选择大小与所需块大小匹配的段。 

每次分配都会从段中删除一个位置，并将其分成最多两个较小的段。 高度按降序分配，以便较早的位置充当后面位置的全局分隔符。 

重要的实现细节是段选择必须匹配精确的大小，而不仅仅是任何段。 这确保了每个塔都嵌入在一个区域中，其最终可见性完全由局部结构决定。 

## 工作示例

 考虑一个小的概念示例，其中 n = 5 且 a = [2, 0, 2, 0, 0]。 我们按 a 对索引进行排序，首先给出值为 2 的索引。 

最初该段是 [0, 5)。 我们为满足要求 2 的第一个塔选择一个大小为 3 的段。假设我们将其放置在 [0, 3) 内的位置 0 处，分成 [1, 3) 并保持其他段不变。

 ## 边缘情况

 像 n = 2 且 a_i = 0 这样的最小情况检查算法是否可以分配两个孤立的塔，而不会强制不必要的可见性。 该结构将每个部分放入尺寸为 1 的段中，不产生任何连接。 

所有 a_i 都相等的完全对称情况迫使算法一致地分配相同大小的段。 由于段分割始终保留总长度，因此每个放置都会继续找到有效的段而不会产生矛盾。 

一个塔具有接近 n - 1 的大 a_i 的情况确保第一次放置消耗整个阵列段，这对应于首先放置最主要的塔。 这证实了按降序处理是必要的，因为首先放置较小的要求会破坏唯一有效的全局段。
