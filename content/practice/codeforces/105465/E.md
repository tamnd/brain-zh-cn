 ## 解决方案
 ## 问题理解

 我们得到一棵树，其中每个操作都以非常特定的方式改变结构。 一种类型的操作插入一个新顶点并将其恰好连接到一个现有顶点，从而有效地创建一个新叶子。 另一种类型删除一条边及其两个端点，但仅当一个端点当前是叶子且另一个端点此时度数最多为 2 时。 

该过程一直持续到没有顶点为止，目标是最小化两种类型组合的操作总数。 

输入是 n 个节点上的一棵树。 输出是使用两个允许的操作完全擦除所有节点所需的最小可能操作数。 

约束 n 高达 2 · 10^5 立即排除任何尝试模拟该过程或显式考虑边子集的解决方案。 任何可行的方法都必须在树的大小上是线性的或接近线性的，通常为 O(n) 或 O(n log n)。 这已经表明答案必须来自树的结构属性，很可能是动态规划公式。 

当贪婪地思考时，就会出现一个微妙的问题。 尽快重复删除任何有效边是很诱人的，但这可能会在配置中捕获高度顶点，使它们暂时无法使用，从而迫使稍后执行不必要的插入操作。 例如，在一棵星形树中，在没有计划的情况下任意移除叶子可能会留下一个具有太多依赖性的中心顶点，需要人工顶点来解决。 

另一个失败案例来自路径类树。 如果我们总是删除第一个可用的叶父对，我们最终可能会隔离一个剩余的顶点，如果不插入新顶点就无法删除该顶点。 这表明局部贪婪配对没有捕获进程的全局结构。 

## 方法

 暴力破解的想法是模拟所有有效的操作序列。 在每一步中，我们都会搜索端点满足删除条件的任何边，尝试将其删除，并递归地探索所有可能性，同时在卡住时在何处插入顶点进行分支。 这正确地对过程进行了建模，但很快就变成指数级的，因为每次删除都会改变程度并创建新的选择，而插入操作会进一步扩展状态空间。 

关键的观察结果是，删除操作总是删除恰好两个顶点，并且从根本上消耗了相邻节点对。 如果我们忽略中间度约束并关注最终一起删除的端点，则每次删除都对应于选择原始树的一条边，以便两个端点在过程的某个阶段配对。 

这将问题重新构建为沿边对原始顶点进行配对，并限制每个顶点最多可以参与来自删除操作的一个此类配对。 此类配对未覆盖的任何顶点都必须使用插入的顶点进行处理，因为剩余节点只能通过将其与新创建的叶子配对来删除。 

因此我们需要的结构是树上的最大匹配。 每条匹配边对应于删除两个原始顶点的一次删除操作。 每个不匹配的顶点都会强制引入辅助顶点和附加操作来消除这两个顶点。 

如果M是树中最大匹配的大小，则在M次操作中直接删除2M个顶点。 剩余的 n − 2M 个顶点每个都需要一个插入顶点，并且每个这样的顶点恰好贡献一次额外的移除操作。 这导致总共 n − M 次操作。 

因此，问题完全简化为计算树中的最大匹配，这是一个经典的树动态编程任务。

 ## 算法演练

 我们使用有根动态规划来计算树中的最大匹配。 

1. 以任意节点（例如节点 1）为树的根，并定义父子结构。 
2. 对于每个节点u，维护两个值。 第一个表示当 u 不强制向上匹配其父级时，u 的子树中的最佳匹配大小。 第二个表示当 u 已经与其父级匹配时的最佳匹配大小，这意味着 u 不能用于与其子级的任何匹配。 
3. 在后序遍历中处理节点，以便在节点本身之前计算节点的所有子节点。 
4. 对于节点 u，通过对所有子节点 v 求和，计算 u 已与其父节点匹配的状态，其中 v 可以自由选择其最佳内部匹配。 这是因为 v 无法与 u 或以上任何内容匹配。 
5. 对于u不向上匹配的状态，从所有孩子处于自由状态的同一基线开始。 然后考虑将 u 与一个子 v 匹配。如果 u 与 v 匹配，则 v 无法使用 u 的边缘，因此 v 必须切换到其“与父级匹配”状态，而所有其他子级仍保持自由状态。 我们对所有孩子做出最好的选择。 
6.整棵树的最大匹配大小是在“与父节点不匹配”状态下为根计算的值。 
7、最终的答案就是n减去这个最大匹配值。 

重要的结构思想是，一旦一个节点与一个邻居匹配，它就不能参与任何其他匹配，这使得每个节点的决策成为本地选择与哪个子节点（如果有）配对。 

### 为什么它有效

 DP 强制匹配中的每条边都只选择一次，并且不会在多个匹配边中使用任何顶点。 树中的任何匹配都可以根据这种父子结构进行分解，因此每个有效的全局匹配恰好对应于一个有效的 DP 配置。 节点最多选择一个子节点进行匹配的转换捕获了匹配的排他性约束，而“与父节点匹配”状态则确保了树中向上的一致性。 有效匹配和 DP 状态之间的这种双射保证了最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

parent = [-1] * n
order = []
stack = [0]
parent[0] = -2

while stack:
    u = stack.pop()
    order.append(u)
    for v in g[u]:
        if v == parent[u]:
            continue
        parent[v] = u
        stack.append(v)

dp0 = [0] * n
dp1 = [0] * n

for u in reversed(order):
    base = 0
    for v in g[u]:
        if v == parent[u]:
            continue
        base += dp0[v]

    dp1[u] = base

    best = base
    for v in g[u]:
        if v == parent[u]:
            continue
        cand = base - dp0[v] + dp1[v] + 1
        if cand > best:
            best = cand

    dp0[u] = best

ans_matching = dp0[0]
print(n - ans_matching)
```该代码首先使用迭代 DFS 构建树的有根表示，因此递归深度不会成为问题。 数组 dp0 和 dp1 实现了前面描述的两种 DP 状态。 dp1对应于节点已经与其父节点匹配的情况，因此它只能独立累积子节点的贡献。 dp0 允许将节点与一个选定的子节点进行匹配的额外可能性，这是通过暂时删除该子节点的自由贡献并将其替换为匹配的配置加上一条边来实现的。 

最后的减法 n − M 直接将最大匹配大小转换为所需操作的数量。 

## 工作示例

 考虑一棵由四个节点组成的小型路径形树：1-2-3-4。 

| 节点| dp1（与父级匹配）| dp0（最佳内部）|
 | --- | --- | --- |
 | 4 | 0 | 0 |
 | 3 | 0 | 1 |
 | 2 | 1 | 1 |
 | 1 | 1 | 2 |

 根值 dp0(1) 等于 2，意味着最大匹配使用两条边。 答案变成 4 − 2 = 2 次操作。 这对应于配对 (1,2) 和 (3,4)，每次删除直接删除两个节点。 

现在考虑一棵星形树，中心 1 连接到 2、3、4。 

| 节点| dp1 | dp0 |
 | --- | --- | --- |
 | 2,3,4 | 0 | 0 |
 | 1 | 0 | 1 |

 最大匹配为 1，因为只有一个叶子可以与中心配对。 答案是 4 − 1 = 3 次操作。 移除一对后，剩下两片叶子，需要基于插入的配对，从而强制进行额外的操作。 

这些示例展示了 dp0 如何捕获最佳可能的配对结构，同时尊重每个节点最多参与一个匹配的边。

import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * n
    order = [0]
    parent[0] = -2
    stack = [0]
    order = []

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            stack.append(v)

    dp0 = [0] * n
    dp1 = [0] * n

    for u in reversed(order):
        base = 0
        for v in g[u]:
            if v == parent[u]:
                continue
            base += dp0[v]

        dp1[u] = base

        best = base
        for v in g[u]:
            if v == parent[u]:
                continue
            best = max(best, base - dp0[v] + dp1[v] + 1)

        dp0[u] = best

    return str(n - dp0[0])
