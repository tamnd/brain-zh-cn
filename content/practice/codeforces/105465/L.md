 ## 解决方案
 ## 问题理解

 我们有一个网格$n$行和$m$列。 对于每一列$j$，我们必须准确选择$a_j$将细胞涂成黑色。 所有其他单元格保持白色。 只要每列黑色单元格的数量是固定的，每列内的选择是自由的。 

绘制后，我们考虑在行中严格向下移动、在列中严格向右移动的黑色单元序列。 换句话说，我们选择黑色单元格，以便行索引和列索引都沿着序列增加。 在所有这样的序列中，我们测量最大可能的长度，这个值称为惩罚。 

我们的任务不仅仅是计算固定着色的惩罚，而是选择着色本身，以使最长的递增序列变得尽可能小。 

关键的难点在于，每列的选择会影响跨列可以形成多少个“兼容链”。 尽管列在包含多少个单元方面是独立的，但全局结构受到网格上单调序列的约束。 

这些约束足够严格，以至于任何显式模拟序列或尝试所有放置的解决方案都是不可能的。 所有测试用例的单元总数最多为$2 \cdot 10^5$，这意味着任何解决方案的总网格大小都必须接近线性或线性对数。 

一种简单的方法可能会尝试显式构建一个网格，然后计算所有黑色单元格上的 LIS$O(NM \log (NM))$。 这对于一个固定网格来说很好，但它并不能解决优化问题：我们必须选择布局以最小化 LIS 本身。 即使对于小网格，任何对布局的暴力都会呈指数级爆炸。 

当列的要求非常大或非常小时，就会出现微妙的边缘情况。 例如，如果所有$a_j = n$，每个单元格都是黑色的，LIS 是$\min(n,m)$，因为我们可以对角线行走。 另一方面，如果每个$a_j = 1$，我们可以小心地将单元格放置在一行中以强制 LIS 为 1，但粗心的放置可能会意外地创建跨列的递增链。 

核心挑战是我们控制垂直位置，但 LIS 取决于跨列的相对顺序。 

## 方法

 如果我们从暴力角度思考，对于每一列，我们可以选择大小的任何子集$a_j$。 即使是单个列也已经有$\binom{n}{a_j}$的可能性，因此配置的总数是天文数字。 即使我们以某种方式修复了配置，计算所有黑色单元格上的 LIS 也需要花费$O(K \log K)$， 在哪里$K$是黑细胞的数量，但瓶颈不是评估，而是构建。 

因此，真正的问题不是如何计算 LIS，而是如何塑造网格，以便不存在长的递增链。 

关键的观察结果是，LIS 这里的行为就像部分有序集中的匹配问题：行和列强加了乘积顺序。 一个经典的观点是，这样一个网格中的 LIS 对应于在黑色单元偏序集中选择一条链。 

为了最小化最大链长度，我们希望“展平”结构，以便长链不能跨越许多列。 各栏目贡献$a_j$黑色单元格，创建长链的唯一方法是在增加的列中找到增加的行。 所以问题就归结为控制我们向右移动时可以“向上”的次数。 

重新解释结构的一个有用方法是逐列。 假设我们从左到右处理列。 如果一列有许多黑色单元格，则会为未来的列创建潜在的延续点。 如果它很少，就会限制可能的链。 

最佳结构结果是双重意义上的贪婪和贪婪：我们在每列中尽可能高地填充黑色单元，或者以结构化方式尽可能低地填充黑色单元，以便最小化可到达链长度的“边界”。 出现的实际不变量是答案由前缀和的次数决定$a_j$超过的倍数$n$，这对应于可以形成多少完整的链“层”。 

更具体地说，如果我们想象从上到下扫描行，每行最多可以支持每列链中的一个元素，限制因素就变成了在累积列需求时溢出行容量的次数。 每次累计总和$a_j$跨越多个$n$，我们被迫将 LIS 长度增加一。 

这将问题转化为计算总需求的分层包装$a_j$成行，每一层对应一个 LIS 单元。 最小可能的 LIS 正是分配列需求时所需的完整“行层”的最大数量。 

这将整个问题简化为列上的简单累积。

 ## 算法演练

 1. 计算黑色单元格总数$S = \sum a_j$。 这代表我们必须在网格中分配多少个单元“放置”。 
2.想象一下逐行填充网格，其中每行最多可以容纳$m$单元格，但列约束迫使我们分布$a_j$每列中的项目。 
3. 观察任何递增链每行最多可以占用一个单元格，因此每一整层$n$相同垂直对齐的放置迫使增加深度的可能性。 
4. 如果我们将每列需求视为垂直堆叠，则模拟需要多少个完整行容量，而不是显式构建网格。 
5. 按顺序处理列，维护当前 LIS 层中剩余多少“未使用的行槽”的运行计数器。 
6. 放置时$a_j$物品，首先消耗剩余的插槽。 如果$a_j$超过可用槽位，开始新层，相应地增加答案。 
7. 创建的层数是可能的最少 LIS。 

这种贪婪分配起作用的原因是，在每一列中，我们可以自由地将黑色单元放置在任何位置，因此我们始终可以对齐它们以重用早期层中的现有行，直到容量耗尽。 只有溢出才会强制创建新的严格增加的级别。 

### 为什么它有效

 该构造隐式地维护了每个 LIS 层对应于一组不相交的行，这些行可以支持跨列的非递减序列。 由于链必须严格增加行，因此每一层每行最多可以贡献一个元素。 贪婪过程确保我们永远不会打开新层，除非所有先前的行已经被先前列的分配饱和。 因此，每次我们创建新层时，我们都会证明任何重新排列都无法避免最大链长度的增加。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        # total cells
        total = sum(a)

        # minimal LIS equals ceil(total / n)
        ans = (total + n - 1) // n

        print(ans)

        # construct grid
        grid = [['.' for _ in range(m)] for _ in range(n)]

        # fill column by column, top to bottom
        row = 0
        for j in range(m):
            for _ in range(a[j]):
                grid[row][j] = '#'
                row += 1
                if row == n:
                    row = 0

        for r in grid:
            print(''.join(r))

if __name__ == "__main__":
    solve()
```该代码将解决方案分为两个独立的部分：计算最优惩罚并构建实现它的有效网格。 

公式$\lceil \frac{\sum a_j}{n} \rceil$来自将网格解释为$n$每行向潜在增加的链层贡献一个单位。 每次我们耗尽所有行时，我们都被迫开始一个新层，这与增加 LIS 完全对应。 

然后，该结构简单地以循环自上而下的方式分布黑色单元。 这保证了在每一列中我们尊重精确的计数，同时确保黑色单元格尽可能均匀地分布在行上，避免意外的长单调链。 

一个常见的实现陷阱是忘记重置行索引模$n$，这会错误地将布局偏向较低的行并人为地增加 LIS。 

## 工作示例

 考虑一个案例$n = 3, m = 3$,$a = [2, 1, 2]$。 总计为$5$，所以答案是$\lceil 5/3 \rceil = 2$。 

我们模拟放置：

 | 步骤| 专栏 | 剩余a[j] | 行索引 | 行动|
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 2 | 0 | 地点#|
 | 2 | 0 | 1 | 1 | 地点#|
 | 3 | 1 | 1 | 2 | 地点#|
 | 4 | 2 | 2 | 0 | 地点#|
 | 5 | 2 | 1 | 1 | 地点#|

 生成的网格中的黑色单元格相当均匀地分布在各行中，从而防止链长于 2。 

这证实了包装行索引会强制行的重用并限制链的增长。 

现在考虑$n = 2, m = 4, a = [1,1,1,1]$。 总计为$4$，所以答案是$2$。 

| 步骤| 专栏 | 行|
 | --- | --- | --- |
 | 1 | 0 | 0 |
 | 2 | 1 | 1 |
 | 3 | 2 | 0 |
 | 4 | 3 | 1 |

 我们交替行，确保不存在长度为 3 的链。 任何以不同方式对齐放置的尝试都会创建长度为 3 的对角线，但循环分布会阻止这种情况发生。

 ## 边缘情况

 一个关键的边缘情况是当一列单独消耗所有行时，例如$n=3, m=2, a=[3,1]$。 第一列填充所有行，迫使下一个放置重新启动新层。 该算法自然地处理这个问题，因为行索引回绕并再次从顶部开始填充，但 LIS 边界已经由总溢出确定。 

另一种情况是当所有$a_j = 1$， 例如$n=5, m=5$。 这里的最优策略必须避免构建对角链。 循环放置可确保在列增加太多之前行重复，从而打破潜在的严格增加序列。 

最后，当$n=1$，每个放置都被强制放入同一行，因此 LIS 等于非零列的总数$a_j$。 公式$\lceil \sum a_j / n \rceil$正确地退化为总和本身，匹配不可避免的链长度。
