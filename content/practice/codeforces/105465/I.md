 ## 解决方案
 ## 问题理解

 我们得到了一个集合$n$立方体，每个立方体有六个可见的数字。 每个立方体都可以定向，使其六个面中的任何一个成为顶面，这意味着对于每个立方体，我们可以选择其六个数字中的任何一个作为它贡献的数字。 

如果我们可以选择立方体的一些子集并为每个选定的立方体分配其可见数字之一，则数字被认为是可构造的，这样得到的数字序列形成一个不带前导零的正整数。 未选择的立方体将被简单地忽略。 每个选定的立方体只贡献一位数。 

任务是确定最小的$k$不能以这种方式形成的正整数。 

关键约束是$n \le 100$， 尽管$k \le 10^5$。 这立即表明可表示数字的集合是由相对较小的组合结构控制的，但缺失数字的查询范围可能很大。 任何显式地逐一检查每个整数并从头开始重新计算可行性的方法都会太慢，因为测试单个数字需要解决最多 100 个立方体的约束分配问题。 

当涉及零时，会出现微妙的边缘情况。 如果前导数字不能为零，则像 102 这样的数字无效，即使立方体包含零。 另一个边缘情况是未使用的立方体很重要：我们可以完全跳过立方体，这意味着除非仔细建模，否则较长的数字不一定更难或更容易单调。 

例如，如果所有立方体都只包含数字{1,2}，那么像3、4、5、6、7、8、9、10这样的数字在结构化方式中都是不可能的，并且跳过立方体允许任意长度控制。 天真的“总是使用所有立方体”的假设是错误的。 

## 方法

 强力解释将尝试按升序枚举整数并检查每个整数是否可以形成。 对于每个数字，我们需要决定是否可以将数字分配给立方体的子集，以便每个选定的立方体提供与数字的数字匹配的数字。 这本质上是数字位置和立方体之间的二分匹配或子集选择问题。 

如果我们检查一些长度的可行性$L$，一种自然的方法是尝试立方体的所有子集和所有分配，这是指数级的$n$。 即使我们优化可行性检查，我们仍然需要处理最多$10^5$候选编号，每个编号都可能需要$O(nL)$或者更糟糕的匹配逻辑。 这变得完全不可行。 

关键的结构观察是，可行性仅取决于哪些数字出现在哪些立方体上，而不取决于数值本身，除了逐位约束之外。 自从$n$很小，我们可以反过来思考：我们可以隐式地描述所有可构造数字的特征，然后枚举补码，而不是检查一个数字是否可构造。 

关键的简化在于，每个立方体独立地提供一小组数字，并且数字中的每个数字位置都需要一个支持该数字的不同立方体。 这将问题转化为位置和立方体之间的二分匹配可行性检查。 自从$n \le 100$，基于 DFS 的标准匹配足够快。 

然后，我们按升序生成数字，但不是从头开始重新计算，而是在收集后重用匹配、修剪和提前停止$k$不可能的数字。

 ## 算法演练

 我们将这个问题视为反复测试是否可以使用可用的立方体构建一个数字。 

### 步骤 1：预处理立方体数字可用性

 对于每个立方体，我们存储它可以显示的数字。 这是一个布尔数组，每个立方体的大小为 10。 这允许在尝试将数字分配给立方体时进行恒定时间检查。 

这种结构是必要的，因为每次可行性检查都会重复询问立方体是否可以提供数字。 

### 步骤 2：定义数字的可行性

 给定一个数字，我们将其数字视为位置。 我们需要将每个数字位置分配给包含该数字的不同立方体。 这是位置和立方体之间的二分匹配问题。 

我们立即拒绝带有前导零的数字，因为根据定义这些数字是无效的。 

### 第三步：匹配配方

 我们构建了一个基于 DFS 的从数字位置到立方体的二分匹配。 每个多维数据集最多可以使用一次，因此我们在 DFS 期间维护多维数据集上的已访问数组。 对于每个位置，我们尝试将其分配给任何支持其数字的立方体。 

如果所有位置都可以匹配，则该数字是可构造的。 

### 步骤 4：按升序枚举数字

 我们从 1 开始向上迭代整数，将每个整数转换为字符串，并测试可行性。 如果不可行，我们会将其添加到答案列表中。 收集后我们就停下来$k$这样的数字。 

排序确保了正确性，因为我们想要最小的不可能数字。 

### 第 5 步：尽早停止

 一旦我们收集完毕$k$不可能的数字，我们停止枚举。 这很重要，因为答案可能很大，但我们不需要更进一步。 

### 为什么它有效

 核心不变量是可行性检查正确地捕获了“每个数字可以分配给包含它的不同立方体”的条件。 DFS 匹配确保没有立方体被重复使用，并且每个有效的分配都对应于数字的有效构造。 由于我们按升序扫描数字并且仅记录失败，因此结果列表正是不可能数字的排序集。 没有数字被错误地跳过，因为每个整数都经过独立测试的可构造性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

cubes = []
for _ in range(n):
    faces = list(map(int, input().split()))
    ok = [False] * 10
    for d in faces:
        ok[d] = True
    cubes.append(ok)

sys.setrecursionlimit(1000000)

def can_make(s):
    if s[0] == '0':
        return False

    m = len(s)
    match = [-1] * n

    def dfs(i, vis):
        for j in range(n):
            if not vis[j] and cubes[j][int(s[i])]:
                vis[j] = True
                if match[j] == -1 or dfs(match[j], vis):
                    match[j] = i
                    return True
        return False

    # try to match each position
    for i in range(m):
        vis = [False] * n
        if not dfs(i, vis):
            return False
    return True

ans = []
x = 1

while len(ans) < k:
    s = str(x)
    if not can_make(s):
        ans.append(x)
    x += 1

print(*ans)
```立方体预处理步骤为每个立方体的数字可行性构建一个快速查找表。 这样可以避免在匹配过程中重复扫描人脸。 

这`can_make`函数执行基于 DFS 的数字到多维数据集的分配。 每个数字位置都是独立处理的，对于每个数字位置，我们尝试找到一个可以容纳它的立方体。 已访问数组可防止在单个 DFS 调用中重新访问多维数据集，并且`match`array 强制每个立方体最多使用一次。 

外循环只是枚举整数并收集那些未通过可行性测试的整数。 

一个微妙的点是重置`vis`每个数字位置而不是每个整个匹配尝试。 这确保每个 DFS 探索新的增广路径，而不同位置之间不会发生干扰。

 ## 边缘情况

 一种重要的边缘情况是当数字包含重复的数字但立方体不支持重复时。 例如，如果只有一个立方体包含数字 7，那么即使只有 7 是可能的，但 77 是不可能的。 匹配公式可以正确检测到这一点，因为单个立方体不能被分配两次。 

另一个边缘情况是导致零拒绝。 对于立方体仅包含零和一个数字的输入，像 10 或 100 这样的数字在结构上可能看起来可行，但如果第一位数字为零，则必须拒绝。 显式前导零检查可确保在匹配之前排除这些内容。 

最后一个边缘情况是$n$很大，但数字变化很小。 即使存在许多立方体，可行性仍然受到数字覆盖范围的限制，并且匹配确保我们不会错误地假设丰富的立方体允许所有数字。
