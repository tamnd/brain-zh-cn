 ## 解决方案
 ## 问题理解

 我们得到一个开始完全无色的网格，其中$n$行和$m$列。 然后我们应用一系列操作。 每个操作都会选择一行和一列，并使用选定的非白色颜色绘制该行和该列中的每个单元格。 如果某个单元格在操作中被多次绘制，则接触它的最新操作将覆盖其颜色。 

处理完所有操作后，最终的网格完全由操作顺序和分配给它们的颜色选择决定。 如果至少一个单元格的最终颜色不同，则认为两个最终网格不同。 

任务是计算如果对于每个操作，我们独立选择以下任何一个，可以生成多少个不同的最终网格$k$颜色。 

这些约束非常严格，以至于任何模拟网格甚至跟踪每个单元状态的解决方案都立即不可行。 跨测试用例的操作总数最多为$2 \cdot 10^5$，这迫使解在操作数上呈线性或接近线性。 任何尝试重新计算网格或传播每个单元更新的方法都将超出时间限制几个数量级。 

当操作重复相同的行列对时，会出现一个微妙的问题。 一个天真的想法可能是独立处理每个操作并乘以$k^q$。 这会失败，因为不同的操作可能会相互覆盖，使得早期的选择在许多情况下变得无关紧要。 例如，如果所有操作都针对相同的行和列，则只有最后一个操作对每个单元格很重要，因此有效着色的数量只是$k$， 不是$k^q$。 

另一种故障模式是假设可以独立处理行和列。 它们不是独立的，因为单个操作同时着色，并且交互取决于操作的顺序。 

## 方法

 暴力方法会尝试模拟所有可能的操作颜色分配。 对于每个操作，我们选择其中之一$k$颜色，模拟网格上的效果，并计算最终结果。 这是正确的但不可行，因为它探索了$k^q$即使投入很小，可能性也是巨大的。 

我们需要避免跟踪整个网格，而是关注运营的结构效应。 关键的观察是，只有影响每行或列的最后一个操作才能确定其最终的可见状态。 一旦一行被后面的操作“覆盖”，任何影响它的早期操作都与该行的贡献无关，除非它们发生在以后不会被覆盖的不同区域。 

这导致根据“第一次行或列由于被后续操作覆盖而变得不相关”来重新构建该过程。 每个操作要么引入新的影响，要么变得多余，具体取决于其行或列稍后是否会被覆盖。 

我们从最后到第一个处理操作。 当我们看到一对时$(x, y)$，如果两行$x$和列$y$已经被后面的操作“阻塞”了，那么这个操作就不能贡献任何新的东西。 如果至少有一个未被阻止，那么此操作将在选择颜色方面提供新的自由度。 处理后，我们将行和列标记为阻塞。 

这种反向贪婪结构之所以有效，是因为一旦后面的操作考虑了行或列，任何早期的操作都不能影响最终网格中幸存的任何未分配区域。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(k^q \cdot nm)$|$O(nm)$| 太慢了 |
 | 最佳 |$O(n + m + q)$|$O(n + m)$| 已接受 |

 ## 算法演练

 我们以相反的顺序处理操作，并维护哪些行和列已被后续操作“覆盖”。 

1. 初始化两个布尔数组，一个用于行，一个用于列，初始值均为 false。 这些表示行或列是否已被后续操作所占用。 
2. 将“活跃操作”贡献计数器初始化为零。 每当我们发现一个仍然影响至少一个新行或新列的操作时，它就会贡献一个乘法因子$k$。 
3. 从最后到第一个迭代操作。 对于每个操作$(x_i, y_i)$,检查是否行$x_i$已标记或已列$y_i$已标记。 
4. 如果两行$x_i$和列$y_i$已标记，此操作不会引入任何新的可见自由度，可以忽略。 
5. 否则，此操作会贡献一个新的独立颜色选择，因此将答案乘以$k$，然后标记行$x_i$和列$y_i$如所覆盖。 
6. 继续，直到处理完所有操作。 

最终的答案是乘积累加模$998244353$。 

### 为什么它有效

 关键的不变量是，在反向扫描中的任何点，每个未标记的行和列都对应于网格的一个区域，该区域仍然可能受到早期操作的影响。 当我们处理一个至少涉及一个未标记的行或列的操作时，这是该区域第一次被反向“认领”，这意味着它的颜色选择仍然是自由和独立的。 一旦我们标记了它的行和列，所有影响它们的早期操作就不能引入新的独立选择，因为它们影响的任何单元格已经由前向时间中的后续操作确定。 这确保了每个贡献操作恰好对应于一个独立因素$k$，并且没有依赖性被计算两次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

t = int(input())
for _ in range(t):
    n, m, k, q = map(int, input().split())
    ops = [tuple(map(int, input().split())) for _ in range(q)]

    row_used = [False] * (n + 1)
    col_used = [False] * (m + 1)

    ans = 1

    for x, y in reversed(ops):
        if row_used[x] and col_used[y]:
            continue
        ans = (ans * k) % MOD
        row_used[x] = True
        col_used[y] = True

    print(ans)
```其实现直接反映了反向贪婪的思想。 我们首先存储所有操作，因为我们需要向后处理它们。 两个布尔数组跟踪行或列是否已被后续操作声明。 

关键细节是条件`if row_used[x] and col_used[y]`。 这确保我们仅在无法引入任何新的独立着色选择时跳过操作。 如果行或列仍然空闲，我们必须计算此操作，因为它确定了逆过程中新的影响边界。 

乘以$k$恰好在引入新的独立选择时发生。

 ## 边缘情况

 一个微妙的边缘情况是当许多操作重复同一对时$(x, y)$。 该算法仅将最后一个此类操作视为有意义的反向操作，但如果是第一次引入行或列，则每次重复仍然可以做出贡献。 例如，通过重复相同的操作，反向扫描仅计算一个贡献，正确地产生$k$，因为第一个处理的事件已经标记了行和列。 

另一个边缘情况是所有操作共享同一行但不同的列。 相反，第一个操作将标记行，一旦行和列都已标记，后续操作将被跳过。 这正确地避免了过度计数，并反映出只有第一个遇到的边界才会引入自由选择。 

这些案例证实，不变量与单个操作无关，而是与它们是否在反时限中引入了先前未见过的行列边界有关。
