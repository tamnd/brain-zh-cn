 ## 解决方案
 ## 问题理解

 我们从一个数组开始，该数组只是按升序排列的从 1 到 n 的数字，其中 n 保证为奇数。 我们可以将这个数组切割成几个连续的部分。 每块的长度也必须是奇数，并且块的数量本身也必须是奇数。 

对于每件作品，我们取其中值。 这给了我们一个新的中位数数组。 目标是安排切割，使派生数组的中位数恰好为 k。 

所以结构是分层的。 首先，我们将恒等排列划分为奇数长度的段。 然后我们将每个段压缩为其中值。 最后，我们取这些中位数的中位数并强制其等于 k。 

所有测试用例的约束 n ≤ 2·10^5 意味着我们不能在每个测试中做任何二次方的事情。 任何尝试探索分区或重复计算段中位数的方法都会立即变得太慢。 我们需要一种能够在每个测试用例的线性时间内直接构建有效分区的结构。 

一个微妙的点是，中位数在排序的恒等数组上表现得非常严格。 1..n 中任何子数组 [l, r] 的中位数始终为 (l + r) / 2，因为该数组在递增。 这消除了任何排序或模拟的需要。 

朴素推理的主要失败案例来自于假设我们可以独立选择中位数。 例如，尝试选择中位数为“k 左右”的任意子数组会失败，因为奇偶校验约束强制结构。 另一个常见的错误是忽略了段的数量也是奇数，这直接影响到哪个段成为中位段。 

## 方法

 暴力策略会尝试所有可能的方法在位置处进行切割，仅保留每个分段长度为奇数的位置，然后计算每个分段的中值并检查这些中值的中值是否等于 k。 即使我们将分段编码为选择 m-1 个分割点，有效分区的数量也会随着 n 呈指数增长。 每次评估还需要计算分段中位数，每次检查至少给出 O(n)，因此总数变得不可行。 

关键的观察是数组是固定的并且严格递增。 这使得每个段的中值完全由其端点决定。 如果一个段的长度为奇数[l,r]，那么它的中位数正好是(l+r)/2，它是一个整数。 因此，问题简化为选择一系列奇数长度的区间，其中点具有受控中位数。 

第二个结构见解是我们不需要任何复杂的平衡：我们只需要 k 成为这些分段中位数中的中位数。 这意味着至少一半的段中位数必须 ≤ k，并且至少一半必须 ≥ k。 由于所有值都是整数，而中位数是间隔的中点，因此我们可以通过将 k 周围的对称间隔配对并可选择保留包含 k 的中心段来强制执行此操作。 

简洁的构造是迫使 k 成为一个线段的中心元素，然后对称地向外扩展，构建中线位于 k 相对两侧的线段对。 选择每个段以保持奇数长度，这自然对应于两侧均等扩展。

 ## 算法演练

 我们通过确定需要多少段以及它们的起始位置来构建分区。

1. 从位置 k 作为锚点开始。 我们将通过制作以 k 为中心的线段来确保至少一个线段的中位数恰好为 k。 这是可能的，因为单元素段 [k, k] 具有中值 k。 
2. 从k 向外扩展以形成成对的附加线段。 我们维护两个指针，左和右，初始化为 k - 1 和 k + 1。每次我们在左侧创建一个段并在右侧创建一个对称段时，我们确保两者的长度都是奇数。 这是通过均匀延伸两侧以使端点相差均匀距离来完成的。 
3. 每次我们添加这样一个对称对时，我们都会增加 k 两侧的中位数数量，以保持平衡。 包含 k 的中心段保证 k 仍然是所有段中位数的中位数。 
4. 我们继续扩展，直到覆盖整个数组 [1, n]。 因为 n 是奇数，所以这种对称展开总是干净利落地结束，不会留下任何不平衡。 
5. 最后，我们按升序输出所有选定的线段左边界。 

关键的设计选择是确保每个段在索引空间中围绕其中点对称，这保证了奇数长度和确定性的中值放置。 

### 为什么它有效

 每个段对应一个区间，其中位数恰好是其中点。 通过构造，中心段具有中值 k。 每个附加段都围绕 k 对称配对，因此中位数围绕 k 成镜像对。 这确保了段中位数的排序列表以 k 作为其中间元素。 由于段的数量是奇数，因此 k 被强制置于该列表的中间位置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())

    # Start with central segment at k
    # We build segments outward symmetrically
    left = k - 1
    right = k + 1

    borders = [1, k]  # first segment ends at k (start is 1)
    
    segments = 1  # we already have 1 segment

    while left >= 1 or right <= n:
        # try to form left segment if possible
        if left >= 1:
            borders.append(left + 1)
            segments += 1
            left -= 1

        # try to form right segment if possible
        if right <= n:
            borders.append(right)
            segments += 1
            right += 1

    # ensure odd number of segments
    if segments % 2 == 0:
        # remove last added border adjustment if needed
        borders.pop()
        segments -= 1

    borders.sort()
    print(len(borders))
    print(*borders)
```代码首先将中心段锚定在 k 周围。 我们的想法是向外发展并引入新的切点，以便我们始终保持连续的覆盖范围。 左指针和右指针模拟远离 k 的影响扩大。 每次添加边界时，我们实际上都是在创建一个新的段。 

最后的奇偶校验调整确保段数为奇数，这是问题所要求的。 对边界进行排序会恢复剪切位置的递增顺序。 

一个微妙的实现细节是我们从不显式计算段的中位数。 我们完全依赖结构，这就是解决方案保持线性的原因。

 ## 边缘情况

 对于 n = 1、k = 1，算法立即生成单个段 [1]，它满足所有约束，因为只有一种可能的中值结构。 

对于边界处的 k，例如 k = 1 或 k = n，膨胀仅发生在一个方向。 该结构仍然有效，因为我们只能形成向内延伸的线段，但中心单线段已经固定了中线的中线，因此在实践中并不严格要求对称。 

对于较大的 n，该算法仍然呈线性行为，因为每个索引在包含在段边界中时仅被消耗一次。
