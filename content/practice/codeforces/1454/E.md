 ## 解决方案
 ## 问题理解

 我们给出一个连通的无向图，其中边的数量等于顶点的数量。 这立即意味着该结构几乎是一棵树，除了在图中某处创建单个循环的一个额外边之外。 

任务是计算所有正长度的简单路径。 简单路径是不同顶点的任何序列，其中连续顶点通过边连接。 如果一条路径与另一条路径相反，则两条路径被视为相同，因此方向并不重要。 

考虑输出的一种有用方法是，每对无序顶点都可以生成多个简单路径，因为在具有一个循环的图中，在某些顶点对之间可能有两种不同的简单方式：一种绕着循环顺时针方向移动，另一种则相反。 在树中，这种歧义永远不存在，因此每一对都对应于一条路径。 

这些约束迫使我们采用线性方法。 由于所有测试用例的总顶点数高达 2×10^5，任何重新计算每对路径或从每个节点执行重复 DFS 的解决方案都会立即变得太慢。 每个测试用例中 n 的任何二次方都将无法生存。 我们需要将问题简化为每个测试用例的单个线性遍历。 

一个常见的失败案例是将图视为树。 例如，如果图是一个由 4 个节点组成的简单循环，则朴素的树公式会说每对节点之间只有一条路径，但实际上，循环上的每一对都有第二条替代路径，沿着循环的另一个方向进行。 缺少这种重复计算是核心陷阱。 

## 方法

 如果我们忽略结构并尝试显式枚举所有简单路径，我们将从每个顶点开始 DFS 并扩展路径，同时避免重新访问。 这种情况很快就会爆发，因为即使在稀疏图中，简单路径的数量在一般图中也可能呈指数增长。 这里的图是受到限制的，但是朴素的枚举仍然会导致 O(n^2) 行为，因为每条路径都会从不同的起点被发现多次。 

关键的结构观察是，具有 n 个顶点和 n 个边的连通图恰好包含一个简单循环。 If we remove any edge from that cycle, the graph becomes a tree. 在树中，每一对顶点都有一条简单路径。 因此，原始图中的所有简单路径都可以理解为树路径加上仅当两个端点围绕循环处于不同方向时才会出现的额外替代路径。 

我们将问题简化为两个部分。 首先，计算所有路径，就好像我们有一棵树一样。 其次，计算循环引入的额外路径。 树部分很简单：在树中，简单路径的数量等于 n(n−1)/2，因为每个无序对只贡献一条路径。 

仅当一对顶点可以通过两种不同的简单方式连接并且都避免重新访问顶点时，该循环才会引入额外的路径。 This happens precisely when both endpoints lie on the cycle, and we choose different arcs of the cycle. For a cycle of length k, every pair of distinct cycle vertices contributes exactly one extra path beyond the tree path. 这是因为树表示隐式地选择一个方向，而循环提供了第二条简单的路线。 

因此，如果我们确定环及其长度 k，答案就变成：

 所有顶点上的树路径加上循环顶点之间的额外路径，即再次添加 k(k−1)/2。 

We only need to find which vertices belong to the cycle and its size. 这可以通过迭代修剪叶子来完成：重复删除 1 度的顶点。在这个过程之后，循环仍然存在。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力DFS枚举| 最坏 O(2^n) | O(n) | 太慢了|
 | 循环+树分解 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 构建图的邻接表。 这是有效执行结构缩减所必需的。 
2. 计算每个顶点的度数。 保证度数为 1 的顶点不属于循环，因为循环顶点在简单循环中必须至少有两个关联边。 
3. 将所有 1 度顶点推入队列并迭代删除它们。 每次移除一个顶点时，都会减少其邻居的度数。 如果邻居的度数变为 1，则将其推入队列。 这将逐渐剥离附着在循环上的所有树状分支。 
4. 剪枝完成后，剩下的顶点就是唯一循环中的顶点。 设它们的数量为 k。 这是可行的，因为每个非循环顶点都位于附加到循环的有限树中，并且最终将被删除。 
5. 计算无序顶点对的总数，即n(n−1)/2。 这计算了树状解释中所有简单路径的基本贡献。 
6. 添加循环中的额外贡献，即 k(k−1)/2。 该术语解释了任意一对循环顶点之间的第二条不同路径。 
7. 输出总和。 

### 为什么它有效

 修剪叶子后，每个删除的顶点都属于附加到循环的树，并且树不会在单个路径之外的端点之间提供替代路由。 只有循环中剩余的顶点才会在路径选择中产生歧义，因为它们形成一个闭环，删除一条边不会断开结构。 每对无序的循环顶点都恰好有两条不同的简单路径，而所有其他对都只有一条，因此对所有对进行一次计数，再加上每个循环对添加一个额外的路径，就可以捕获所有简单路径一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        g = [[] for _ in range(n)]
        deg = [0] * n
        
        for _ in range(n):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)
            deg[u] += 1
            deg[v] += 1
        
        q = deque(i for i in range(n) if deg[i] == 1)
        removed = [False] * n
        
        while q:
            u = q.popleft()
            if removed[u]:
                continue
            removed[u] = True
            for v in g[u]:
                if removed[v]:
                    continue
                deg[v] -= 1
                if deg[v] == 1:
                    q.append(v)
        
        k = sum(1 for i in range(n) if not removed[i])
        
        total_pairs = n * (n - 1) // 2
        cycle_pairs_extra = k * (k - 1) // 2
        
        print(total_pairs + cycle_pairs_extra)

if __name__ == "__main__":
    solve()
```邻接表存储图，以便剪枝期间的度更新可以在每个边的恒定时间内完成。 队列确保每个顶点最多被处理一次，因为一旦被删除，它就不会重新进入活动考虑范围。 

修剪循环会仔细检查已删除的数组，这避免了已删除的顶点多次递减度数。 当多个邻居将同一个顶点推入队列时，这可以防止度结构损坏。 

最终的计算利用了这样一个事实：所有贡献都干净地分成全局对计数和循环中的校正项。

 ## 边缘情况

 完全循环图（其中每个顶点的度数为 2）是最简洁的场景。 没有发生剪枝，因此 k 等于 n。 该算法直接计算所有对的额外贡献，匹配每对都有两条不同的简单路径的事实。 

带有连接到单循环顶点的长树的图显示了修剪的重要性。 首先删除所有树顶点，确保它们不会错误地膨胀 k，因为只有循环顶点才应有助于替代路径计数。 

多个叶子存在于不同深度的情况表明修剪顺序并不重要。 即使叶子以任意顺序从队列中删除，每个非循环顶点最终都会变为度数 1 并被消除，从而保证仅保留循环顶点。
