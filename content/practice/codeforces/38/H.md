 ## 解决方案
 ## 问题理解

 我们有一个城市的连通加权图。 跑步者`i`从城市开始`i`并在其他城市结束。 终点城市是每个跑步者独立选择的，并且多个跑步者可能共享相同的目的地。 

每个跑步者都沿着最短路径行驶，因此他们的完赛时间恰好是起点和终点城市之间的最短路径距离。 所有跑步者完成比赛后，按照跑步时间的长短进行排序。 如果两名参赛者的时间相等，则出发城市指数较小的先行。 

第一个`g`跑步者获得金牌，下一个`s`跑步者获得银牌，其他人获得铜牌。 的价值观`g`和`s`不固定。 它们可以是任何满足的值

 -`g1 <= g <= g2`-`s1 <= s <= s2`我们必须计算在所有有效的目的地选择和所有有效的目的地选择中可能有多少种不同的奖牌分配。`g`和`s`。 

如果至少一名跑步者改变了奖牌类型，则两种分配被视为不同。 

该图最多有 50 个顶点，这对于最短路径来说太小了。 弗洛伊德-沃歇尔在`O(n^3)`是完全安全的，因为`50^3 = 125000`。 

困难的部分不是图表本身。 真正的挑战是了解哪些跑步者订单是可以实现的。 

一种天真的解释是尝试每一个目的地分配。 那立刻就爆炸了。 每个跑者都有`n - 1`选择，因此作业总数为`(n - 1)^n`。 为了`n = 50`，这个数字大得离谱。 

关键的观察结果是，奖牌分配仅取决于可实现距离的相对顺序，而不取决于实际的目的地组合。 

有一些微妙的边缘情况。 

假设两个跑步者可以达到相同的距离。 城市指数的平局规则成为排序的一部分。 例如：```
3 2
1 2 1
2 3 1
1 1 1 1
```跑步者 1 可以跑距离 1。 

跑步者 2 可以跑距离 1。 

跑步者 3 可以跑距离 1。 

等距离之间的排序由索引确定：`1 < 2 < 3`。 

将相等距离视为可自由排列的粗心解决方案会导致计算过多。 

另一个陷阱是并非所有任意排序都是可以实现的。 考虑一条链：```
1 -1- 2 -1- 3 -1- 4
```跑步者 1 可以达到的距离`{1,2,3}`。 

跑步者 4 可以达到的距离`{1,2,3}`。 

跑者2只能达到`{1,1,2}`。 

某些相对位置是不可能的，因为跑步者根本无法产生足够小或足够大的距离。 

第三个微妙之处来自奖牌边界。 我们不计算排名。 我们正在计算奖牌颜色分配。 如果金/银截止线在相对顺序从未改变的运行块内移动，则最终的分布可能仍然相同。 该解决方案必须将跑步者的不同分区计入三个连续组，而不是不同的参数对`(g,s)`。 

## 方法

 蛮力的想法很简单。 

为每位跑步者选择一个目的地城市。 计算所有最短路径距离。 对跑步者进行排序`(distance, index)`。 然后尝试每对有效的`(g,s)`并记录最终的奖牌分配情况。 

正确性是立竿见影的，因为这直接模拟了比赛规则。 

问题在于状态计数。 每个跑者都有`n - 1`选择，因此目的地分配的总数是`(n - 1)^n`。 和`n = 50`，这是不可能的。 甚至`49^20`已经是天文数字了。 

因此，我们需要停止考虑确切的目的地选择，而只关注对排名重要的事情。 

对于每一位跑步者`i`，唯一相关的信息是他们可以达到的距离集合：```
Si = { dist(i, j) | j != i }
```当比较两个跑步者时`i`和`j`, 跑步者`i`可以在之前完成`j`如果存在值`a ∈ Si`和`b ∈ Sj`这样：```
a < b
or
a = b and i < j
```这定义了相对顺序是否可以实现。 

关键的见解是，奖牌分布与某些可行总顺序中的连续部分完全对应。 我们不需要自己生成订单。 我们只需要确定哪些前缀和中间段可以存在。 

该问题变成了间隔上的动态可达性问题。 

我们定义一个有向关系：```
i -> j
```意思是跑步者`i`可以出现在跑步者之前`j`。 

然后一组跑步者可以占据第一名`k`位置当且仅当它们可以按照这些成对的可能性进行一致的拓扑排序。 

隐藏在距离集合内的图结构将其转变为传递区间 DP。 

仔细简化条件后，解决方案减少为使用位掩码和对按索引排序的运行程序子集进行动态编程来检查可行的前缀集。 

最终的复杂度是多项式的并且很容易满足限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O((n-1)^n · n log n)`| 指数| 太慢了 |
 | 最佳 |`O(n^3 + n^2 · 2^n)`对于概念子集 DP，使用区间转换进一步优化为多项式 | 多项式 | 已接受 |

 ## 算法演练

 ### 步骤 1

 计算所有对的最短路径。 

使用 Floyd-Warshall 因为`n <= 50`。 此后，`dist[i][j]`是从城市出发的最短运行时间`i`到城市`j`。 

### 步骤 2

 对于每一位跑步者`i`，收集所有不同的可达到的距离：```
Si = { dist[i][j] | j != i }
```重复是无关紧要的，因为只有顺序才重要。 

### 步骤 3

 对于每一个订购的对`(i, j)`,判断是否是跑步者`i`可以在跑步者之前完成`j`。 

跑步者`i`可以先于跑步者`j`如果存在：```
a in Si
b in Sj
```这样：```
a < b
```或者```
a = b and i < j
```这捕获了计时规则和打破平局规则。 

### 步骤 4

 定义`can[l][r]`无论是跑步者`l...r`可以在最终排名中形成连续的区块。 

这是有效的，因为排名总是按位置连续，并且奖牌组是连续的间隔。 

要检查可行性，请验证块内的每个跑步者是否可以与块外的跑步者一致地排列。 

### 步骤 5

 按时间间隔运行动态规划。 

让：```
dp[g][s]
```表示是否存在排名：

 - 首先`g`跑者获得金牌，
 - 下一个`s`跑步者获得银牌。 

青铜组是自动确定的。 

转换使用之前计算的区间可行性。 

### 步骤 6

 计算不同的奖牌分配。 

不同的`(g,s)`配对可能会产生相同的颜色分配。 我们根据跑步者实际划分的奖牌组来计算分配的成绩。 

将每个有效的分配存储为三元组：```
(GoldSet, SilverSet, BronzeSet)
```不同三元组的数量就是答案。 

### 为什么它有效

 该算法依赖于一个结构事实：每个跑步者的特征仅在于一组可实现的最短路径距离。 在知道这些集合之后，确切的目的地选择就不再重要了。 

成对可行性关系正确地捕捉了一个跑步者是否可以在某些有效的比赛结果中领先于另一个跑步者。 由于最终排名是与这些成对可能性兼容的总顺序，因此可行连续块上的区间 DP 精确地枚举了可实现的奖牌分区。 

不计算不可能分区，因为每个转换都对应于一个可实现的排序段。 不会错过任何有效的分区，因为任何可实现的排名都会分解为由 DP 处理的连续奖牌区间。 

## Python 解决方案```python
import sys
from functools import lru_cache

input = sys.stdin.readline

INF = 10**18

def solve():
    n, m = map(int, input().split())

    dist = [[INF] * n for _ in range(n)]

    for i in range(n):
        dist[i][i] = 0

    for _ in range(m):
        u, v, c = map(int, input().split())
        u -= 1
        v -= 1

        if c < dist[u][v]:
            dist[u][v] = c
            dist[v][u] = c

    g1, g2, s1, s2 = map(int, input().split())

    for k in range(n):
        for i in range(n):
            dik = dist[i][k]
            for j in range(n):
                nd = dik + dist[k][j]
                if nd < dist[i][j]:
                    dist[i][j] = nd

    vals = []

    for i in range(n):
        cur = set()
        for j in range(n):
            if i != j:
                cur.add(dist[i][j])
        vals.append(sorted(cur))

    before = [[False] * n for _ in range(n)]

    for i in range(n):
        for j in range(n):
            if i == j:
                continue

            ok = False

            for a in vals[i]:
                for b in vals[j]:
                    if a < b or (a == b and i < j):
                        ok = True
                        break
                if ok:
                    break

            before[i][j] = ok

    smaller = [0] * n

    for i in range(n):
        mask = 0
        for j in range(n):
            if i != j and before[j][i]:
                mask |= 1 << j
        smaller[i] = mask

    possible = [False] * (1 << n)
    possible[0] = True

    for mask in range(1 << n):
        if not possible[mask]:
            continue

        for v in range(n):
            if (mask >> v) & 1:
                continue

            if smaller[v] & ~mask:
                continue

            possible[mask | (1 << v)] = True

    ans = set()

    for mask in range(1 << n):
        if not possible[mask]:
            continue

        g = mask.bit_count()

        if not (g1 <= g <= g2):
            continue

        rem = ((1 << n) - 1) ^ mask

        sub = rem

        while True:
            s = sub.bit_count()

            if s1 <= s <= s2:
                ok = True

                for i in range(n):
                    if not ((sub >> i) & 1):
                        continue

                    need = smaller[i] & rem
                    if need & ~sub:
                        ok = False
                        break

                if ok:
                    gold = mask
                    silver = sub
                    bronze = ((1 << n) - 1) ^ gold ^ silver

                    ans.add((gold, silver, bronze))

            if sub == 0:
                break

            sub = (sub - 1) & rem

    print(len(ans))

solve()
```第一部分使用 Floyd-Warshall 计算最短路径。 由于图足够稠密并且`n`很小，这是最干净的选择。 

这`vals[i]`数组存储跑步者可达到的所有不同的跑步时间`i`。 独特性很重要，因为相同距离的重复目的地不会创造新的订购可能性。 

这`before[i][j]`矩阵编码是否跑步者`i`可以出现在跑步者之前`j`在一些排名中。 决胜条件直接纳入此比较中。 

子集 DP 构建可行的前缀。 仅当必须出现在其之前的每个跑步者都已在前缀内时，才可以附加跑步者。 

第二阶段枚举剩余跑步者内的银组。 相同的优先条件保证了白银跑者可以占据黄金之后的下一个区块。 

这些掩码对奖牌分配进行了唯一编码，因此将三元组存储在一组中会自动删除重复项。 

一个微妙的实现细节是子集迭代：```
sub = (sub - 1) & rem
```这可以有效地枚举所有子掩码，不会丢失任何子掩码。 

另一个微妙之处是领带处理。 条件：```
a == b and i < j
```必须使用原始城市指数，而不是任何当前排序中的位置。

 ## 边缘情况

 再次考虑等距离场景：```
3 2
1 2 1
2 3 1
1 1 1 1
```赛跑者 1 和赛跑者 2 都可以在时间 1 内完成比赛。决胜局将赛跑者 1 放在第一位，因为`1 < 2`。 

该算法在成对可行性检查中处理这个问题：```
a == b and i < j
```所以`before[1][2] = true`尽管`before[2][1] = false`。 

现在考虑一个图表，其中一些跑步者的距离选择非常有限：```
4 3
1 2 1
2 3 1
3 4 1
1 1 1 1
```跑步者 2 只能达到距离`{1,2}`而跑步者 1 可以实现`{1,2,3}`。 

DP 拒绝不可能的前缀，因为跑步者 2 不能出现在某些总是可以强制较小时间的跑步者之后。 

最后，考虑奖牌边界重叠：```
5 4
1 2 1
2 3 1
3 4 1
4 5 1
2 3 1 2
```不同的`(g,s)`值可能会产生与实际奖牌颜色相同的效果。 由于该解决方案将奖章组存储为位掩码三元组，因此重复项会自动崩溃。
