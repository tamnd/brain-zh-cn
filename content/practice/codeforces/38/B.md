 ## 解决方案
 ## 问题理解

 我们给出了标准 8 × 8 棋盘上两个棋子的位置，一个车和一个马。 他们的起始位置保证是安全的，这意味着车不会攻击马，马也不会攻击车。 

我们必须在空的格子上再放置一名马，这样放置后，三块棋子就不会互相攻击。 新的骑士必须避免攻击车，避免攻击现有的骑士，也避免被他们攻击。 由于骑士的攻击是对称的，这意味着没有一对棋子可以互相攻击。 

棋盘尺寸固定为仅 64 格。 这完全改变了问题的性质。 即使是独立检查每个方格的暴力方法在操作方面也是微乎其微的。 我们永远不需要高级优化或预处理，因为最大工作量受一个小常数的限制。 

直接模拟就足够了。 对于每个板单元，我们可以问：

 1. 广场已经被占用了吗？ 
2.它是否受到车的攻击？ 
3.是否受到现有骑士的攻击？ 
4. 新的骑士会攻击车吗？ 
5. 新的骑士会攻击现有的骑士吗？ 

最后两项检查实际上与检查方格是否受到这些棋子的攻击相同，因为攻击对于骑士来说是相互的，而车的移动是沿行和列对称的。 

有几种容易被忽略的边缘情况。 

一个常见的错误是忘记新骑士不能放置在已占领的方格上。 考虑：```
a1
c2
```广场`a1`无效，因为车已经占用了它，并且`c2`无效，因为现有的骑士占据了它。 

另一个错误是只检查车是否攻击新马，而忘记马也可以攻击车。 对于骑士来说，这种区别在概念上很重要，即使攻击关系是对称的。 例子：```
d4
f5
```将新骑士放置在`e2`无效，因为骑士在`e2`攻击`d4`。 

边界处理是错误的另一个来源。 骑士的动作可以走到棋盘外。 例如：```
a1
h8
```从`a1`，像这样移动`(-2, -1)`或者`(1, -2)`是无效的，必须被忽略。 粗心的实现可能会访问无效索引或错误地计算不存在的方块。 

## 方法

 最直接的想法就是蛮力。 棋盘只有 64 个方格，因此我们可以尝试将新的马放置在每个方格上，并验证结果配置是否安全。 

对于每个候选方格，我们执行恒定时间检查：

 - 方格中不得包含车或马。 
- 车不得攻击候选人。 
- 现有的骑士不得攻击候选人。 

车攻击同一行或同一列的任何方格。 骑士根据其八种可能的 L 形动作进行攻击。 

即使我们每次都检查所有 64 个方格并测试所有八个骑士动作，总的工作量仍然很小。 粗略地说，这是在一千个原始操作之下。 

由于电路板尺寸是固定的，因此暴力解决方案在实践中已经是最佳的。 这里不可能出现有意义的渐近改进。 关键的观察结果是搜索空间的大小是恒定的，因此详尽的检查是预期的解决方案。 

唯一真正的挑战是正确、干净地实施国际象棋攻击规则。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 奥(64) | O(1) | O(1) | 已接受 |
 | 最佳 | 奥(64) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取车位和现有马位。 
2. 将国际象棋坐标转换为数字棋盘坐标。 

列`a`通过`h`变得`0`通过`7`，和行`1`通过`8`变得`0`通过`7`。 数字坐标使运动检查变得更加容易。 
3. 存储八个可能的骑士移动偏移。 

一名骑士走过`(±2, ±1)`或者`(±1, ±2)`。 
4. 遍历板上的每个方格。 

由于棋盘只有8×8，直接检查所有位置是最简单、最安全的。 
5. 如果该方格已经包含车或现有的马，则跳过该方格。 

该问题只允许放置在空的方块上。 
6. 检查车是否攻击候选方格。 

车沿着行和列攻击，因此如果方格与车共享任一坐标，则该方格无效。 
7. 检查现有的骑士是否攻击候选方格。 

比较一下八骑士运动模式的坐标差异。 
8. 如果两个棋子都没有攻击候选方格，则视为有效。 
9. 打印最终计数。 

### 为什么它有效

 该算法明确检查可能放置新骑士的每个方格。 仅当满足所有攻击条件时，方才算作数。 由于每个候选方格都被检查一次并且每个无效条件都被拒绝，因此最终计数精确地包含有效的位置而没有其他内容。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def parse(pos):
    x = ord(pos[0]) - ord('a')
    y = int(pos[1]) - 1
    return x, y

def knight_attacks(x1, y1, x2, y2):
    dx = abs(x1 - x2)
    dy = abs(y1 - y2)
    return (dx, dy) in [(1, 2), (2, 1)]

rook = input().strip()
knight = input().strip()

rx, ry = parse(rook)
kx, ky = parse(knight)

answer = 0

for x in range(8):
    for y in range(8):

        # occupied square
        if (x, y) == (rx, ry) or (x, y) == (kx, ky):
            continue

        # rook attack
        if x == rx or y == ry:
            continue

        # knight attack
        if knight_attacks(kx, ky, x, y):
            continue

        answer += 1

print(answer)
```这`parse`函数将国际象棋符号转换为从零开始的坐标。 这避免了整个解决方案中重复的字符算术。 

这`knight_attacks`helper 隔离了骑士的移动逻辑。 它不是显式地生成所有移动，而是使用坐标差异。 骑士的攻击总是会产生绝对的差异`(1, 2)`或者`(2, 1)`。 

嵌套循环遍历每个棋盘方块。 由于电路板尺寸是固定的，这种详尽的搜索既简单又高效。 

检查的顺序对于可读性比性能更重要。 我们首先拒绝被占领的方格，然后是车的攻击，然后是马的攻击。 每个被拒绝的条件都会立即跳过不必要的工作。 

一个微妙的细节是行转换。 国际象棋行写为`1`通过`8`，但数组本质上是从零开始的。 减一将保留所有坐标`[0, 7]`。

    out = io.StringIO()
    sys.stdout = out

    return out.getvalue().strip()

 ## 边缘情况

 考虑输入：```
a1
h8
```车攻击整个第一行和第一列。 骑士上`h8`仅攻击`f7`和`g6`，因为所有其他马的动作都在棋盘之外。 

该算法自然地处理这个问题。 每个方格都是独立检查的，并且永远不会生成棋盘外的骑士移动，因为该解决方案直接比较坐标差异而不是构建目的地。 

现在考虑：```
d4
f5
```粗心的解决方案可能只检查车是否攻击新马，而忘记新马可以攻击现有棋子。 

假设我们尝试将新马放在`e3`。 坐标差为`d4`是`(1, 1)`，所以车是安全的。 区别于`f5`也是`(1, 2)`，意思是骑士互相攻击。 该算法拒绝平方，因为`knight_attacks`返回真。 

最后，考虑占用方块的处理：```
a1
c2
```该算法明确跳过`(0, 0)`和`(2, 1)`在进行任何攻击检查之前。 如果没有这个条件，实现可能会错误地将已占据的位置计为合法位置。
