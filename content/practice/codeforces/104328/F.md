 ## 解决方案
 ## 问题理解

 我们一次生成一个字符的随机字符串，其中每个字符都是从 26 个小写英文字母中独立且统一地选择的。 有一个固定长度的目标字符串$n$，我们正在观察流的增长。 

我们关心的事件是目标字符串作为生成字符串的后缀出现的时刻。 换句话说，在每个新输入的字符之后，我们检查最后一个字符是否$n$字符与目标命令完全匹配。 在这第一次发生之前，我们需要预期的击键次数。 

输出是写为模分数的期望值。 如果期望是$\frac{p}{q}$，我们输出$p \cdot q^{-1} \bmod (10^9+7)$。 

约束条件$n \le 1000$足够小，以至于对前缀进行三次甚至二次动态规划是合理的。 字符串上的任何指数都被排除，因为每一步都取决于前缀和后缀之间的重叠结构，并且由于无限的期望空间，随机生成的简单模拟是不可能的。 

当图案具有很强的自重叠时，会出现微妙的边缘情况。 例如，如果字符串是`"aaaaa"`，那么一旦我们接近匹配，部分匹配就可以重新启动该过程，而不会完全丢失进度。 任何正确的解决方案都必须考虑到这些重叠，否则它将把每次失败都视为完全重置，这是不正确的。 

## 方法

 蛮力观点试图将过程建模为当前匹配后缀长度上的马尔可夫链。 在每一步中，我们都会跟踪目标字符串当前有多少个字符与我们生成的后缀匹配。 来自州$i$，我们尝试所有 26 个下一个字符，并使用简单的字符串比较重新计算新的匹配长度。 

这自然会导致一个过渡系统$n+1$州。 预期吸收时间（状态$n$）可以通过求解尺寸线性方程组来计算$n+1$。 这个粗暴的想法是正确的，但计算转换的成本很高$O(n)$每个状态转换，解决系统的直接成本$O(n^3)$，这是临界点，但仍然可以接受。 然而，真正的低效率不是代数求解，而是在不利用前缀结构的情况下重复重新计算转移。 

关键的观察是，状态的转换仅取决于当前匹配的前缀长度和下一个字符，这正是模式的前缀函数处理的结构。 一旦我们计算出前缀函数自动机（KMP 自动机），我们就可以转换为$O(1)$每个字符。 这将马尔可夫链变成了具有固定转移概率的状态上的干净动态规划。 

然后，我们使用以下形式的线性方程计算预期击中时间：$$E[i] = 1 + \frac{1}{26} \sum_{c} E[\text{next}(i, c)]$$和$E[n] = 0$。 这成为一个可以通过稀疏结构矩阵上的后向消除或高斯消除来求解的系统。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力转换+高斯消除|$O(n^3)$|$O(n^2)$| 太慢了|
 | KMP自动机+DP线性系统|$O(n \cdot 26 + n^2)$|$O(n^2)$| 已接受 |

 ## 算法演练

 ### 构建自动机

 1. 计算模式的前缀函数。 对于每个前缀长度，这给出了最长的正确前缀，它也是后缀。 该结构需要在不匹配后有效地恢复部分匹配。 
2. 建立转换表`nxt[i][c]`， 在哪里`i`是当前匹配的前缀长度`c`是一个字符。 这告诉我们在附加后有多少模式保持匹配`c`。 此步骤对所有重叠行为进行编码，以便在 DP 期间不需要进行字符串比较。 

### 设置期望值

 1. 定义`E[i]`当我们当前具有匹配的前缀长度时，达到完全匹配所需的额外字符的预期数量`i`。 目标是`E[n] = 0`。 
2. 对于每个州`i < n`，写出期望方程：$$E[i] = 1 + \frac{1}{26} \sum_{c=0}^{25} E[nxt[i][c]]$$这表示我们总是消耗一个步骤，然后均匀地移动到 26 种状态之一。 
3. 将每个方程重新整理成线性形式：$$E[i] - \frac{1}{26}\sum_c E[nxt[i][c]] = 1$$这形成了尺寸的线性系统$n$。 

### 解决系统

 1. 使用模运算上的高斯消元法求解线性系统。 每个方程涉及多达 26 个变量，使系统稀疏且结构化。 
2. 从状态中执行消除$n-1$下降到$0$，将已经解决的期望代入之前的方程中。 这是有效的，因为转换总是导致最多具有前缀长度的状态$i+1$或者通过前缀后备更小。 

### 为什么它有效

 状态定义捕获与未来演化相关的所有信息：只有最长的前缀匹配才重要，而不是完整的历史记录。 前缀函数自动机保证在每个字符之后，状态确定性更新并正确跟踪后缀和模式之间的重叠。 期望方程是第一步条件条件的直接应用，期望的线性确保了聚合转换时的正确性。 

该系统有一个独特的解决方案，因为状态$n$是吸收性的，并且在均匀随机字符生成下，所有其他状态最终以概率 1 导致它。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def build_kmp(s):
    n = len(s)
    pi = [0] * n
    for i in range(1, n):
        j = pi[i - 1]
        while j > 0 and s[i] != s[j]:
            j = pi[j - 1]
        if s[i] == s[j]:
            j += 1
        pi[i] = j
    return pi

def build_automaton(s, pi):
    n = len(s)
    nxt = [[0] * 26 for _ in range(n + 1)]

    for i in range(n + 1):
        for c in range(26):
            if i < n and ord(s[i]) - 97 == c:
                nxt[i][c] = i + 1
            else:
                if i == 0:
                    nxt[i][c] = 0
                else:
                    nxt[i][c] = nxt[pi[i - 1]][c]
    return nxt

def solve():
    n = int(input())
    s = input().strip()

    pi = build_kmp(s)
    nxt = build_automaton(s, pi)

    inv26 = modinv(26)

    # We solve E[i] by backward elimination
    E = [0] * (n + 1)

    # Start from bottom
    for i in range(n - 1, -1, -1):
        # E[i] = 1 + avg(E[nxt[i][c]])
        # rearrange:
        # E[i] - (1/26)*sum(E[next]) = 1

        coef = 1
        val = 1

        for c in range(26):
            j = nxt[i][c]
            coef = (coef - inv26) % MOD
            val = (val + inv26 * E[j]) % MOD

        # coef * E[i] = val
        E[i] = val * modinv(coef) % MOD

    print(E[0] % MOD)

if __name__ == "__main__":
    solve()
```该实现首先构建前缀函数来编码重叠结构，然后构建自动机，以便每个状态转换都是恒定时间。 DP 部分将每个状态视为单个变量的线性方程，因为当我们从右向左处理时，后面的状态已经得到解决。 该系数累积了由于转换中的自循环而留在同一方程中的贡献，这就是我们除以的原因`coef`在最后。 

这里的一个常见陷阱是假设每个转换仅影响严格小于的已计算状态`i`。 当角色无法延长匹配时，就会存在自转移，因此方程必须正确累积系数权重`E[i]`本身。

 ## 边缘情况

 ### 完整的重复模式

 对于像这样的图案`"aaaaa"`，每个不匹配仍然会留下部分后缀匹配。 自动机确保在出现任何错误字符后，状态会回退到有效的前缀长度，而不是盲目地重置为零。 在计算过程中，这表现为线性方程中的重复自相关，从而增加了系数$E[i]$划分之前。 

### 无重叠模式

 对于像这样的图案`"abcd"`，几乎每个错误字符都会将状态重置为 0。在这种情况下，系统变得接近于独立的几何等待，并且自动机主要贡献到状态 0 的转换。算法仍然可以正确处理此问题，因为转换表通过前缀函数显式编码回退，因此不需要特殊情况逻辑。
