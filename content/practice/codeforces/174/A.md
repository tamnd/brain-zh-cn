 ## 解决方案
 ## 问题理解

 我们有几个杯子，里面已经装有不同数量的 Ber-Cola。 瓶子里还剩下一些饮料。 我们必须将剩余的全部量倒入杯子中，以便每个杯子的体积完全相同。 

如果初始金额是`a1, a2, ..., an`瓶子里装有`b`，我们需要确定每个杯子中​​需要加入多少额外的饮料。 添加量必须同时满足两个条件。 首先，总添加量必须等于`b`。 其次，倾倒后，所有杯子的最终体积必须相同。 

限制非常小。 最多有 100 个杯子，每个值最多为 100。即使是二次或三次算法也很容易满足限制。 挑战不在于性能，而在于识别决定解决方案是否存在的数学条件。 

关键的观察是每个杯子都必须以某个共同的值结束`x`。 马克杯用`i`，添加量为：$$c_i = x - a_i$$总添加量必须等于`b`， 所以：$$\sum (x - a_i) = b$$扩展此给出：$$n \cdot x - \sum a_i = b$$它立即确定唯一可能的最终值：$$x = \frac{\sum a_i + b}{n}$$一次`x`众所周知，每一个`c_i`是固定的。 

危险的边缘情况是某些杯子的含量已超过目标值。 在这种情况下，相应的`c_i`变为负值，这是不可能的，因为我们只允许将饮料倒入杯子中，而不能将其取出。 

考虑这个例子：```
2 1
5 1
```倒入后的总量为`7`，因此目标变为`3.5`。 第一个杯子已经包含`5`，大于`3.5`。 达到相同的体积需要去除`1.5`从那个杯子。 正确的输出是：```
-1
```粗心的实现可能会机械地计算公式并打印负值。 

当所有杯子已经相等时，会发生另一种微妙的情况。```
3 6
2 2 2
```目标变为`4`，所以每个杯子都会收到`2`。 输出是：```
2.000000
2.000000
2.000000
```错误地假设不相等的起始值的实现可能会错误地处理这种情况。 

第三种边缘情况是目标变为分数。```
2 1
1 1
```每个杯子的最终数量是`1.5`，所以每个杯子都会收到`0.5`。 这里需要浮点输出。 

## 方法

 暴力思维会从猜测最终的共同金额开始`x`。 对于每一位候选人`x`，我们可以计算每个杯子需要多少，并检查总添加量是否等于`b`。 

由于所有值都很小，我们甚至可以尝试许多可能的具有一定精度的实际值。 该方法在逻辑上是正确的，因为任何有效的解决方案都必须对应于某个共同的最终体积。 问题在于搜索实数是尴尬且不必要的。 即使将搜索离散化也会带来精度问题和无意义的额外工作。 

方程的结构给出了更强大的东西。 每个杯子必须以相同的值结束，这意味着所有添加的金额都直接与一个变量相关`x`。 对方程求和将整个系统折叠成一个公式：$$x = \frac{\sum a_i + b}{n}$$无需搜索。 目标值由总液体守恒唯一确定。 

一旦我们知道`x`，每个答案都很简单：$$c_i = x - a_i$$唯一剩下的有效性检查是是否有任何`c_i`是负数。 如果有一个为负，则无法进行配置。

 ## 算法演练

 1. 阅读`n`,`b`，以及杯子体积的数组。 
2. 计算倾倒后存在的液体总量：$$total = \sum a_i + b$$3. 计算每个杯子的最终等体积：$$x = \frac{total}{n}$$该值是由液体守恒定律强制规定的。 没有其他目标可以满足条件。 
4. 对于每个杯子，计算：$$c_i = x - a_i$$这正是必须添加多少才能达到共同的最终值。 
5.如果有的话`c_i`为负数，打印`-1`并停止。 

负值意味着杯子中的液体已超过目标量，因此均衡需要去除液体。 
6. 否则，打印每个`c_i`小数点后至少有六位数字。 

### 为什么它有效

 该算法依赖于守恒定律。 倒出后的液体总量是固定的，所以如果所有杯子最后的液体量都相同`x`，那么总液体必须等于`n * x`。 这唯一地决定了`x`。 

对于每个杯子，唯一可能的添加量是`x - a_i`。 不存在替代分配，因为更改一个杯子的添加量会改变其最终体积`x`。 

如果每个计算值都是非负的，那么所有杯子确实可以增加到恰好`x`，总添加量自动等于`b`因为如何`x`被导出。 如果任何值为负，则不存在有效解，因为倾倒不能减少液体。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, b = map(int, input().split())
    a = list(map(int, input().split()))

    target = (sum(a) + b) / n

    ans = []

    for value in a:
        add = target - value

        if add < 0:
            print(-1)
            return

        ans.append(add)

    for x in ans:
        print(f"{x:.6f}")

solve()
```第一部分读取输入并计算目标最终体积。 该值直接从瓶子倒空后可用的液体总量中得出。 

该循环计算必须向每个杯子添加多少。 条件`add < 0`是整个可行性测试。 如果杯子已经超过目标液位，我们无法修复这种情况，因为该操作仅允许添加液体。 

答案将被存储并随后打印。 打印用`:.6f`保证小数点后至少六位，满足输出要求。 

一个微妙的细节是在计算目标时使用浮点除法。 使用整数除法会截断小数答案并在以下情况下产生不正确的结果`2 1`带杯子`1 1`。

 ## 边缘情况

 考虑不可能的配置：```
2 1
5 1
```该算法计算：$$target = (5 + 1 + 1) / 2 = 3.5$$对于第一个杯子：$$3.5 - 5 = -1.5$$阴性结果立即触发`-1`。 这是正确的，因为均衡需要从第一个杯子中除去液体。 

现在考虑一个分数目标：```
2 1
1 1
```目标变为：$$(1 + 1 + 1) / 2 = 1.5$$两个杯子都收到`0.5`。 该算法使用浮点除法，因此整数截断不会损失精度。 

最后，考虑一个杯子已经与目标匹配的情况：```
2 100
0 100
```目标变为：$$(0 + 100 + 100) / 2 = 100$$补充内容是：$$100 - 0 = 100$$和$$100 - 100 = 0$$零是允许的，因为我们不需要倒入每个杯子，只需分配整个瓶子，同时以相等的体积结束。
