 **求解时间：** 1m 43s

 ## 解决方案
 ## 问题理解

 我们从一个长度的数组开始`n`充满零。 一次操作选择一个段`[l, r]`并添加`1`到该段内的每个元素。 

给出了最终的数组。 我们必须重建一个能够准确生成该数组的操作序列，同时使用尽可能少的操作。 

关键细节是操作可以自由重叠。 如果一个位置最终有价值`5`，那么恰好有五个选定的线段必须覆盖该位置。 如果不同的位置所需的增量重叠，则可以共享操作。 

这些约束立即排除了任何二次方。 数组长度达到`10^5`，并且值也达到`10^5`。 重复扫描间隔或逐个单元模拟增量的解决方案可以轻松执行`10^10`最坏情况下的操作。 我们需要一些线性或接近线性的东西。 

还有施工要求。 我们不仅需要最小计数，还必须明确输出间隔本身。 由于该语句保证最优答案最多包含`10^5`操作，一个`O(answer)`施工是可以接受的。 

一些边缘情况很容易被错误处理。 

考虑一个严格递增的数组：```
1 2 3 4
```正确答案是四段：```
[1,4]
[2,4]
[3,4]
[4,4]
```一个粗心的贪心试图尽可能延长旧的间隔而不打开新的间隔将会失败，因为每次增加`a[i-1]`到`a[i]`强制额外的时间间隔开始于`i`。 

现在考虑减小值：```
4 3 2 1
```最优的构造是：```
[1,1]
[1,2]
[1,3]
[1,4]
```这里，在第一个位置之后不需要新的间隔。 相反，有些间隔只是提前结束。 始终保持所有间隔有效直到最后的实现会超出后面的位置。 

另一个微妙的情况是数组中包含零：```
2 0 2
```中间的零将左右部分完全分开。 任何区间都不能交叉索引`2`，否则该位置将变为正值。 最优解使用四个独立区间：```
[1,1]
[1,1]
[3,3]
[3,3]
```任何将间隔视为可跨零重用的方法都会产生无效的数组。 

## 方法

 蛮力视角有助于揭示问题的结构。 

假设我们从左到右处理数组。 在位置`i`，我们知道有多少当前活动间隔覆盖它。 如果少于`a[i]`间隔已激活，我们从以下时间开始打开新的间隔`i`。 如果太多间隔处于活动状态，我们会在到达之前关闭一些间隔`i`。 

一种简单的实现将显式跟踪每个活动段并重复搜索要关闭的间隔。 在最坏的情况下，这会变成二次方。 例如，交替模式如下：```
1 0 1 0 1 0 ...
```强制频繁创建和销毁区间。 在活动间隔内重复线性扫描对于`10^5`元素。 

关键的观察是最小操作数完全由数组的增加决定。 

每当：```
a[i] > a[i-1]
```我们必须准确地开始：```
a[i] - a[i-1]
```位置处的新间隔`i`。 

这是没有办法解决的。 现有间隔已经仅贡献`a[i-1]`位置覆盖`i-1`，因此为了进一步提高覆盖范围`i`，附加间隔必须从那里开始。 

相反，如果该值减小，某些间隔将在当前位置之前终止。 

这将问题转化为区间簿记问题。 我们维持所有当前活跃的间隔。 当所需高度增加时，我们会打开新的间隔。 当它减少时，我们在前一个位置关闭足够的间隔。 

堆栈在这里完美地工作。 每个活动间隔仅存储其起始索引。 当一个间隔必须结束时，我们将其弹出并输出`[start, current_position - 1]`。 

每个区间都压入一次，弹出一次，所以整个过程是线性的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 创建一个空堆栈。 每个元素代表一个活动间隔并仅存储其起始位置。 
2. 从左到右迭代数组。 
3.就位`i`， 比较`a[i]`与活动间隔的数量，这很简单`len(stack)`。 
4. 如果活动间隔过多，则重复从堆栈中弹出间隔，直到堆栈大小变为`a[i]`。 

每个弹出的间隔结束于`i - 1`，因为它无法继续到当前位置。 
5. 如果活跃区间太少，则重复推送当前位置`i`入栈，直到栈大小变为`a[i]`。 

每个新的间隔开始于`i`。 
6. 对所有职位继续此过程。 
7. 处理完整个数组后，所有剩余的活动间隔必须在位置结束`n`。 将它们全部弹出并输出它们的片段。 

### 为什么它有效

 不变量很简单：

 加工后位置`i`，堆栈恰好包含覆盖位置的间隔`i`。 

因此它的大小正好是`a[i]`。 

每当目标值增加时，当前位置必然会首次出现额外的覆盖范围，因此新的区间是不可避免的。 稍后启动它们将无法覆盖当前单元格，而较早启动它们会错误地增加先前的单元格。 

每当目标值减小时，某些间隔必须在当前位置之前停止。 结束活动间隔的任何子集都同样有效，因此使用堆栈就足够了。 

由于仅在数学上必要时才会创建新间隔，因此间隔总数是最少的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    stack = []
    ans = []

    for i in range(n):
        pos = i + 1

        while len(stack) > a[i]:
            start = stack.pop()
            ans.append((start, pos - 1))

        while len(stack) < a[i]:
            stack.append(pos)

    while stack:
        start = stack.pop()
        ans.append((start, n))

    print(len(ans))
    print("\n".join(f"{l} {r}" for l, r in ans))

solve()
```堆栈存储当前覆盖当前索引的所有间隔的起始位置。 

当所需高度下降时，间隔必须在当前位置之前终止。 由于所有活动间隔都是等效的，因此弹出任何间隔都有效。 使用堆栈可以实现恒定时间的插入和删除。 

当所需高度上升时，我们在当前位置开始新的间隔。 每一次推送对应一个新操作。 

关闭间隔时会出现一个常见的差一错误。 如果我们当前处于位置`i`，那么移除的间隔必须结束于`i - 1`，因为它们不应该对当前单元格做出贡献。 

另一个微妙的细节是最后的清理。 循环后保持活动状态的间隔必须一直延伸到`n`。 

该解决方案从不直接修改数组。 它只维护每个位置有多少个区间处于活动状态，这足以重建最佳答案。

 | 测量| 复杂性 | 说明|

 这里`k`是最优答案中的运算次数。 

声明保证`k ≤ 10^5`，因此内存使用量和运行时间都在限制范围内。 该算法仅执行线性工作并使用简单的堆栈操作。

 ## 边缘情况

 考虑输入：```
3
2 0 2
```在位置`1`，两个间隔开始。```
stack = [1, 1]
```在位置`2`，所需值变为零。 两个间隔都必须终止于位置`1`。```
[1,1]
[1,1]
```在位置`3`，两个全新的区间开始：```
[3,3]
[3,3]
```该算法正确地防止间隔过零。 

现在考虑：```
4
1 2 3 4
```堆栈大小演变为：```
1 -> 2 -> 3 -> 4
```每次增加都会强制开始一个新的间隔。 没有间隔在结束之前关闭，产生：```
[1,4]
[2,4]
[3,4]
[4,4]
```这证实了增加确定最小操作数的规则。 

最后，考虑：```
5
5 4 3 2 1
```最初五个间隔从位置开始`1`。 

随着目标的减小，间隔一一终止：```
[1,1]
[1,2]
[1,3]
[1,4]
[1,5]
```该算法通过在活动计数变得太大时准确地关闭间隔来正确处理缩小的覆盖范围。
