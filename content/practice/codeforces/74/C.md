 ## 解决方案
 ## 问题理解

 我们有一个`n × m`棋盘。 台球像象一样沿对角线移动，但与象不同的是，它会在棋盘的边界上反射。 当它撞到垂直的墙壁时，方向的水平分量会翻转。 当它碰到水平墙壁时，垂直分量会翻转。 击中角落会使双方翻转。 

如果两个球在其无限反射运动期间最终能够穿过另一个球占据的方格，则两个球会互相攻击。 我们想要尽可能大的方格集合，使得没有两个选定的方格位于同一个台球轨迹上。 

核心问题实际上是：板上存在多少个不同的运动组件？ 同一组件内的每个方块都会攻击该组件中的所有其他方块，因此我们最多可以在每个组件中放置一个球。 由于每个分量至少包含一个正方形，因此答案正是连接轨迹的数量。 

电路板尺寸可达`10^6`。 这立即排除了任何触及每个方格的东西。 甚至一个`O(nm)`遍历需要处理最多`10^12`细胞，这在 2 秒内是不可能的。 解决方案必须仅使用算术`n`和`m`，理想情况下是对数或常数时间。 

棘手的部分是理解反射的实际作用。 天真的解释可能会将运动视为复杂的弹跳，但从几何角度来看，该路径的行为就像无限平铺板上的直线对角线。 错过这种转变会使问题看起来比实际情况要困难得多。 

有几种容易被忽略的边缘情况。 

考虑一块方板：```
4 4
```正确答案是`4`， 不是`1`。 粗心的争论可能会说每条对角线最终都会反射到其他每一条对角线上，但奇偶校验限制阻止了这种情况的发生。 该运动分解为几个独立的循环。 

现在考虑：```
2 3
```答案是`1`。 自从`gcd(1, 2) = 1`，每个方格都属于一条轨迹。 任何单独计算普通主教对角线的方法都会计算过多。 

另一个微妙的情况是：```
2 2
```答案是`2`。 棋盘上只有四个单元，但轨迹却分成两个互不相连的组。 小板很快就会暴露出奇偶校验错误。 

## 方法

 暴力方法将显式地构建运动图。 每个方格最多有四个出射反射对角线方向。 我们可以从每个单元模拟所有可能的台球动作，标记可到达的单元，并计算连接的组件。 

这在概念上是有效的，因为“可以攻击”关系正是图连接性。 如果两个单元位于同一连通分量中，则一个台球轨迹会到达另一个。 

问题在于规模。 董事会可能包含`10^12`正方形。 即使每平方存储一位也是不可能的。 任何对单元格的遍历都会立即超出内存和时间限制。 

关键的观察是反射可以展开。 

想象一下反映板本身，而不是反映边界的方向。 然后台球路径就变成了一条穿过棋盘的无限多个镜像副本的直线对角线。 这是标准的台球展开技巧。 

一旦展开，每一个动作都遵循斜坡线`+1`或者`-1`。 重要的不变量是坐标以某些周期性为模的值。 在分析了反射如何连接单元之后，整个板准确地分为：$$\gcd(n-1, m-1) + 1$$独立的轨迹。 

该公式就是整个解决方案。 

为什么会`n-1`和`m-1`出现而不是`n`和`m`？ 因为反射发生在行和列之间的边界处。 展开运动的有效周期由边界之间的距离决定，即`n-1`垂直和`m-1`水平地。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(纳米) | O(纳米) | 太慢了 |
 | 最佳| O(log(min(n,m))) | O(log(min(n,m))) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`n`和`m`。 
2. 计算`g = gcd(n - 1, m - 1)`。 

展开的轨迹每次都会重复`n - 1`垂直台阶和`m - 1`水平台阶。 它们的相互作用由最大公约数决定。 
3、输出`g + 1`。 

每个残差类别形成一个独立的台球轨迹。 事实证明，此类的数量恰好比 gcd 多 1。 

### 为什么它有效

 将反射板展开成无限多个镜像副本。 台球轨迹变成一条直线对角线。 

当两个单元的展开坐标在同一个无限对角线上时，它们恰好属于相同的轨迹。 周期性结构每重复一次`2(n-1)`垂直和`2(m-1)`水平方向上，不同对角周期的数量取决于这些周期的同步方式。 

同步计数为`gcd(n-1, m-1)`。 这些循环将电路板划分为`gcd(n-1, m-1) + 1`等价类。 由于一个类中的每个单元格都会攻击该类中的所有其他单元格，因此我们最多可以在每个类中放置一个球，并且每个类放置一个球总是可能的。 

## Python 解决方案```python
import sys
from math import gcd

input = sys.stdin.readline

n, m = map(int, input().split())

print(gcd(n - 1, m - 1) + 1)
```实现故意很小，因为所有繁重的工作都发生在数学简化中。 

在获取 gcd 之前，我们将两个维度都减一。 这是最容易犯错误的地方。 台球反射取决于边界之间的距离，而不是单元格本身的数量。 

Python 的内置`math.gcd`已经使用欧几里德算法以对数时间运行，因此它可以轻松处理高达`10^6`。 

决赛`+1`来自轨迹分区的结构。 忘记它会产生在所有情况下都始终太小的答案。

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io
from math import gcd

def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    print(gcd(n - 1, m - 1) + 1)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("3 4\n") == "2\n", "sample 1"

# minimum board
assert run("2 2\n") == "2\n", "minimum size"

# coprime dimensions
assert run("2 3\n") == "1\n", "coprime periods"

# square board
assert run("5 5\n") == "5\n", "equal dimensions"

# large values
assert run("1000000 1000000\n") == "1000000\n", "maximum equal values"

# off-by-one trap
assert run("4 7\n") == "1\n", "gcd(3,6)=3 so answer should be 4"

 ## 边缘情况

 考虑：```
2 2
```该算法计算：

 | 数量 | 价值|
 | --- | --- |
 | n - 1 | n - 1 1 |
 | 米 - 1 | 1 |
 | GCCD | 1 |
 | 答案| 2 |

 一种天真的方法可能会猜测所有四个单元都属于一个轨迹，因为反射在如此小的板上很频繁。 它们实际上分裂成两个独立的周期。 

现在检查：```
2 3
```计算变为：

 | 数量 | 价值|
 | --- | --- |
 | n - 1 | n - 1 1 |
 | 米 - 1 | 2 |
 | GCCD | 1 |
 | 答案| 2 |

 此案例捕获了错误使用的实现`gcd(n, m)`而不是`gcd(n-1, m-1)`。 使用错误的公式会给出`gcd(2,3)+1 = 2`，它在这里意外匹配，但在其他地方失败。 

一个更好的反例是：```
4 7
```正确计算：

 | 数量 | 价值|
 | --- | --- |
 | n - 1 | n - 1 3 |
 | 米 - 1 | 6 |
 | GCCD | 3 |
 | 答案| 4 |

 使用`gcd(4,7)+1`会错误地产生`2`。 这是该问题中典型的差一陷阱。
