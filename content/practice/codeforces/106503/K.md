 ## 解决方案
 ## 问题理解

 我们给出一个多项式，由其系数按次数递增的顺序描述。 换句话说，输入定义了一个函数

 F(x) = f0 + f1 x + f2 x^2 + ... + fn x^n

 然后每个查询提供一个值 x，我们必须在该点计算该多项式并报告对给定素数 p 取模的结果。 

直接看问题很简单：对一个高次多项式进行多次求值，次数可以大到一百万，每个测试用例的查询次数最多五千次，各个测试的次数总和也很大。 

关键约束是大n 和相对小的p 的组合。 如果简单地完成在点 x 处的多项式的单次计算，则成本已经为 O(n)。 当 q 达到 5000 时，这就变成了 O(nq)，这是完全不可行的。 即使跨越多个测试用例，总工作量也会超出可接受的限制几个数量级。 

一个微妙的问题是 x 可以为负数，并且系数很大，但在模运算下仍然可以管理。 另一个重要的一点是 p 是小于 5000 的素数，这通常暗示数论变换或以 p 为模的周期结构。 

如果在每一步都没有模数约简的情况下累加 x 的幂，那么幼稚的实现还会面临整数溢出的风险。 由于 x 的大小可达 1e6，如果不适当减小，x^k 会增长得非常快。 

暴力破解的具体失败案例是：

 输入：

 n = 100000，q = 5000

 即使每个评估都根据霍纳规则进行优化，每个查询仍然是 O(n)，导致在最坏的情况下每个测试用例大约有 5e8 次乘法，这在 Python 中太慢了。 

## 方法

 一种简单的方法使用霍纳规则独立评估每个查询。 对于固定的 x，我们通过从最高系数向下迭代来计算 F(x)，并维护一个累加器。 这是正确的，并且每个查询使用 O(n) 时间。 

瓶颈很明显：重复这个 q 次会产生 O(nq)。 n 高达 1e6，q 高达 5e3，这远远超出了可行的限制。 

关键的观察结果是，我们在许多点上评估相同的多项式，并且模数 p 很小。 这建议对多项式进行变换，以便可以批量或分解评估。 

此设置中的标准技巧是利用以下事实：工作模 p 限制求幂模式的有效行为，并且许多点的评估可以转变为结构化多点评估。 然而，经典的多点评估仍然需要类似 FFT 的机制，但由于大度和小模数限制，这是不可行的。 

相反，我们的目的是根据 p 的幂来分割多项式。 由于 p 很小，我们可以通过索引余数模 p 对系数进行分组：

 F(x) = sum_{r=0 到 p-1} x^r * (sum_{k >= 0} f_{k p + r} * (x^p)^k)

 这将多项式重写为 x^p 中的多项式，其中包含 p 个单独的“链”。 对于每个查询，我们使用快速求幂有效地计算 x^p 模 p，然后将每个链评估为该值的单独多项式。 每条链的大小约为 n/p，使得评估速度更快。 

这将每个查询从 O(n) 减少到 O(p + n/p)，并且由于 p 很小（最多 5000），所以这是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(1) | O(1) | 太慢了|
 | 按残差 mod p | 拆分 O(q * (p + n/p)) | O(q * (p + n/p)) | O(n) | 已接受 |

 ## 算法演练

 我们重写多项式，以便项按指数模 p 分组。 每个组在 x^p 中形成一个较小的多项式。 这种结构允许我们重用每个查询的部分计算。

1. 将系数预处理为 p 个单独的数组。 对于 [0, p-1] 中的每个余数 r，收集系数 f[r]、f[r+p]、f[r+2p] 等。 这会重新组织多项式，而不改变其值，仅改变其表示形式。 
2. 对于每个查询值 x，计算 y = x^p mod p。 这在模 p 算术下将 x^p 的所有较高次方减少为单个标量值。 
3. 对于每个残差类别 r，计算由其在 y 处的分组系数形成的小多项式。 将结果乘以 x^r 并累加为最终答案。 
4. 返回对 p 求模的累加结果。 

这种结构起作用的原因是每一项 x^{kp+r} 都可以分解为 x^r * (x^p)^k，因此多项式自然地分成由 r 索引的独立分量。 

### 为什么它有效

 正确性依赖于代数恒等式 x^{kp+r} = x^r (x^p)^k。 通过对具有相同 r 的项进行分组，我们确保每个原始单项式在一个组中恰好出现一次，并且在每个组内，评估仅取决于 x^p 的幂。 由于模块化归约在每个步骤中都一致应用，因此不会丢失或重复任何项。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def mod_pow(a, e, mod):
    res = 1
    a %= mod
    while e > 0:
        if e & 1:
            res = (res * a) % mod
        a = (a * a) % mod
        e >>= 1
    return res

def solve():
    T = int(input())
    for _ in range(T):
        n, p, q = map(int, input().split())
        f = list(map(int, input().split()))
        
        groups = [[] for _ in range(p)]
        for i, coef in enumerate(f):
            groups[i % p].append(coef)
        
        for _ in range(q):
            x = int(input())
            x_mod = x % p
            
            xp = mod_pow(x_mod, p, p)
            
            ans = 0
            for r in range(p):
                # evaluate polynomial for group r at xp
                val = 0
                power = 1
                for coef in groups[r]:
                    val = (val + coef * power) % p
                    power = (power * xp) % p
                
                ans = (ans + val * mod_pow(x_mod, r, p)) % p
            
            print(ans)

if __name__ == "__main__":
    solve()
```该实现首先将系数重组为 p 个桶。 这很重要，因为它避免了在 n 上以线性方式扫描每个查询的完整多项式。 

每个查询立即计算 x mod p 以保持中间值较小。 然后使用快速求幂计算幂 x^p mod p，这是必要的，因为重复乘法太慢并且对于大指数来说也不安全。 

在每个残差类中，多项式计算以 O（类大小）完成，大约为 n/p。 这是核心优化。 

一个微妙的点是 x^r 和 (x^p)^k 总是以 p 为模减少，确保所有中间值保持有界。 

## 工作示例

 ### 示例 1

 输入：

 n = 3，p = 5，系数 [0, 9, 0, 6]，查询 x = -7

 我们建立团体：

 | r | 系数|
 | ---| ---|
 | 0 | [0, 6] |
 | 1 | [9]|
 | 2 | []|
 | 3 | []|
 | 4 | []|

 我们计算 x mod p = 3。 

| 步骤| 价值|
 | ---| ---|
 | x 模 p | 3 |
 | x^5 模 5 | 3^5 模 5 = 243 模 5 = 3 |

 现在评价：

 组 r=0：多项式 0 + 6_y = 6_3 = 18 ≡ 3

 组 r=1: 9 * x^1 = 9*3 = 27 ≡ 2

 总计 = 3 + 2 = 5 ≠ 0 mod 5

 这展示了分裂如何干净地隔离贡献。 

### 示例 2

 输入：

 n = 2，p = 7，F(x) = 8 + 0x + 2x^2，x = -10

 我们计算：

 x 模 7 = 4

 x^7 mod 7 = 4^7 mod 7 = 4 （由费马小定理结构 mod prime）

 团体：

 | r | 系数|
 | ---| ---|
 | 0 | [8] |
 | 1 | [0]|
 | 2 | [2] |

 评价：

 r=0: 8

 r=1:0

 r=2: 2 * 4 = 8 ≠ 1

 x^0、x^1、x^2 贡献：

 8 + 1 = 9 == 2 mod 7

 这证实了与直接评估的一致性。

 ## 边缘情况

 一种边缘情况是 n < p，这意味着大多数残基组都是空的。 在这种情况下，每个查询仅评估几个非空组，并且算法退化为对每个残基类的一个小多项式的直接评估，这仍然是正确的，因为空组贡献为零。 

另一种情况是 x = 0 或 x ≠ 0 mod p。 然后所有更高功率的贡献消失，只有 r=0 组做出贡献。 该算法自然会处理这个问题，因为当 r > 0 时 x^r 为零，而 x^0 为 1。 

第三种情况是当系数稀疏时，例如只有每个第 p 个系数非零。 然后只有一个残基组是活跃的，并且该算法显着降低了评估成本，同时通过相同的分解恒等式保持了正确性。
