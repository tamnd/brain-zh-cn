 ## 解决方案
 ## 问题理解

 我们正在处理 64 x 64 的位网格，其中每个单元格要么是 0，要么是 1。只有一个单元格是特殊的，Alice 被告知它的坐标。 Alice 可以在网格上执行两次全局操作：她选择一整行并翻转其中的每一位，然后选择一整列并翻转其中的每一位。 经过这一单一修改后，网格将被交给 Bob，他只能看到生成的网格，并且必须识别特殊单元格的位置。 

关键的限制是鲍勃无法访问原始网格，也没有关于爱丽丝翻转了哪一行和哪列的信息。 唯一的通信通道是最终的网格状态本身，因此 Alice 必须将答案编码到转换中，而不是任何外部消息中。 

网格大小固定为 64 x 64，因此有 4096 个单元格。 这立即表明任何编码策略都可以将每个单元视为 12 位空间中的不同状态，因为 2^12 等于 4096。这一观察使得完美的确定性编码成为可能。 

一个天真的想法是尝试通过强制目标单元格在其行或列中具有唯一值模式来“标记”目标单元格，但这会失败，因为行和列翻转会影响大型结构化单元格集，并且任何本地模式都会被未知的初始配置破坏。 另一种天真的尝试是模拟所有可能的翻转选择并尝试通过模式匹配进行解码，但鲍勃没有参考原始网格，因此这基本上是不可能的。 

一个微妙的边缘情况是所选行和列的交叉单元格被翻转两次，这意味着它保持不变。 任何假设行和列翻转在每个单元格都是独立的推理在这一点上都会完全崩溃，如果不仔细处理，就会导致不正确的编码逻辑。 

## 方法

 暴力的观点是认为Alice尝试所有可能的行和列操作对，模拟它们的效果，然后检查Bob是否可以唯一地识别目标。 这在交互意义上是不可行的，因为鲍勃不知道原始网格，因此强力转换不会创建稳定的解码函数。 

关键的转变是停止考虑局部模式，而是将网格视为有限二进制空间中的向量。 每个单元位置都可以编码为唯一的 12 位数字，整个网格可以概括为包含 1 的所有单元的坐标的 XOR。这会产生网格的单个 12 位“签名”。 

翻转行或列对应于对一组固定坐标进行异或运算，与基础值无关。 这将 Alice 的操作转化为将已知的 12 位向量添加到签名中。 整个问题简化为确保 Alice 可以将该签名从其原始值引导到表示隐藏坐标的目标值。 

由于恰好有 4096 个可能的签名和 4096 个可能的操作对，因此转换是双射的，Alice 总能找到生成所需最终签名的行和列对。 

Bob 的工作变得微不足道：重新计算最终网格的签名并将其解码回行和列坐标。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟操作| O(64^4) 或更差 | O(1) | O(1) | 不适用 |
 | 异或矢量编码 | O(64^2) | O(64^2) | O(64^2) 预计算或 O(1) 解码 | 已接受 |

 ## 算法演练

 我们用 12 位整数表示每个单元格，其中高 6 位编码行，低 6 位编码列。

1. 计算每个单元 (r, c) 的编码函数，即 id = r * 64 + c。 这唯一地代表了董事会上的每个职位。 
2. 通过对包含 1 的每个单元格的 id 进行异或运算，计算网格的全局 XOR 签名 S。这将整个网格压缩为单个 12 位值。 
3. 在 Alice 运行期间，从输入网格计算当前签名 S0。 
4.将目标签名T定义为隐藏位置(i,j)的编码。 这就是 T = (i - 1) * 64 + (j - 1)。 
5. 计算差值 delta = S0 XOR T。该差值代表 Alice 必须应用的精确变换，以将当前网格签名转换为目标签名。 
6. 对每对 (x, y) 预先计算翻转行 x 和列 y 作为 12 位 XOR 向量的效果。 这仅取决于网格的几何形状，而不取决于网格值。 
7. 选择效应向量等于 delta 的对 (x, y) 并输出。 
8. 在 Bob 运行期间，从最终网格重新计算签名 S，并通过将其 12 位拆分为行索引和列索引来直接从 S 解码行和列。 

关键的不变量是网格的 XOR 签名在翻转下呈线性行为。 每个操作都对应于对仅由切换的单元确定的固定向量进行异或，因此 Alice 始终在 4096 元素向量空间中应用已知的变换。 因为从 (x, y) 到变换向量的映射恰好覆盖了整个空间一次，所以 Alice 总能达到所需的目标签名。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

N = 64

# precompute effect of choosing row x and column y
# as XOR over affected cell ids
effect = [[0] * N for _ in range(N)]

for x in range(N):
    for y in range(N):
        v = 0
        for c in range(N):
            v ^= (x << 6) | c
        for r in range(N):
            v ^= (r << 6) | y
        v ^= (x << 6) | y  # double counted, cancel it
        effect[x][y] = v

def encode_grid(grid):
    s = 0
    for i in range(N):
        row = grid[i]
        for j in range(N):
            if row[j] == '1':
                s ^= (i << 6) | j
    return s

def decode(s):
    return (s >> 6) + 1, (s & 63) + 1

data = sys.stdin.read().strip().split()
mode = data[0]

if mode == "Alice":
    grid = data[1:1+64]
    i = int(data[65]) - 1
    j = int(data[66]) - 1

    S0 = encode_grid(grid)
    target = (i << 6) | j

    delta = S0 ^ target

    for x in range(N):
        for y in range(N):
            if effect[x][y] == delta:
                print(x + 1, y + 1)
                sys.exit(0)

else:
    grid = data[1:1+64]
    S = encode_grid(grid)
    x, y = decode(S)
    print(x, y)
```Alice 阶段构建网格的压缩 XOR 表示，并计算它必须改变多少才能达到目标单元编码。 预先计算的表确保她始终可以将所需的更改转换为有效的行和列选择。 Bob 阶段忽略所有历史记录，只是重新计算相同的 XOR 签名，这直接揭示了隐藏的坐标。 

一个微妙的实现细节是交叉单元处的取消。 它必须在效果计算中进行两次异或，以反映它包含在行和列翻转中，但物理上仅切换一次。 缺少这一点会导致转换表不正确并破坏双射性。 

## 工作示例

 考虑一个小的 4 x 4 版本来说明该机制。 

Alice 看到一个网格并被告知隐藏单元格是 (3, 3)。 她计算网格中所有 1 的 XOR 签名 S0，并将其与目标编码 T = 3 * 4 + 3 = 15 进行比较。假设 S0 XOR T 等于某个值 delta。 

| 步骤| 价值|
 | ---| ---|
 | S0 | 网格的初始异或|
 | T | 15 | 15
 | 三角洲 | S0 异或 15 |
 | 选择 (x, y) | 配对匹配增量|

 选择 (x, y) 后，Alice 翻转该行和列，生成一个新的网格，其 XOR 签名恰好为 15。 

Bob 接收网格并重新计算其 XOR 签名 S。他获得 15，将其解码回 (3, 3)，并输出正确答案。 

该跟踪表明 Bob 永远不需要了解原始网格，只需要位置上的异或的不变量在编码下保持一致。 

第二种情况是除了假硬币之外所有网格值都相同。 即使在这种极端情况下，S0 仍然是明确定义的，并且 Alice 的变换仅取决于 XOR 差异，而不是绝对结构，因此该方法的行为相同。

import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().strip().split()
    mode = data[0]

    N = 64

    def encode(grid):
        s = 0
        for i in range(N):
            for j in range(N):
                if grid[i][j] == '1':
                    s ^= (i << 6) | j
        return s

    def decode(s):
        return (s >> 6) + 1, (s & 63) + 1

    grid = data[1:1+64]
    if mode == "Bob":
        S = encode(grid)
        return f"{decode(S)[0]} {decode(S)[1]}"
    return "0 0"

 ## 边缘情况

 一个极端的情况是网格不包含任何网格。 在这种情况下，XOR 签名为零，Bob 在编码方案下将其正确解码为 (1, 1)。 这是一致的，因为零对应于有效的坐标编码。 

另一种边缘情况是翻转选定的行和列会导致网格中的所有位切换。 由于双重翻转，交集单元保持不变，保持了异或变换规则的正确性。 尽管视觉结构发生了巨大变化，但签名更新仍然是线性且一致的。 

最后一个微妙的情况是多个不同的网格映射到相同的 XOR 签名。 这是预期的行为，因为 Bob 永远不需要重建精确的网格，只需要重建签名，它唯一地确定 Alice 编码方案中的隐藏坐标。
