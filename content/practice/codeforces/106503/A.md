 ## 解决方案
 ## 问题理解

 我们有一行$n$位置，每个位置要么已经固定为字母`C`或者仍然为空，表示为`?`。 我们必须更换每一个`?`使用大写字母，以便最终字符串完全包含$k$模式的出现次数`SCNUCPC`。 

“匹配”是通过选择起始索引来定义的$i$这样子串来自$i$到$i+6$正是`SCNUCPC`。 允许重叠，因此两个匹配可以共享字符，并且每个有效的起始位置独立计数。 

输出要么是满足约束的完全构造的字符串，要么是不存在此类完成的声明。 

长度$n$可以达到$2 \cdot 10^5$每次测试，最多有$10^3$测试用例的总和$n$受$2 \cdot 10^5$。 这立即排除了任何尝试所有可能的填充的方法`?`或者甚至以天真的方式尝试起始位置的所有子集。 每个测试的任何解决方案都必须是线性或接近线性的。 

一个关键的微妙之处是初始字符串可能已经包含`C`限制可能的位置的字符`SCNUCPC`。 由于我们不被允许改变现有的`C`，任何构造的事件都必须与它们一致。 

自然会出现一些边缘情况。 

如果$n < 7$，不存在长度为 7 的子串，因此只有当$k = 0$。 任何分配`?`尊重固定的`C`有效，例如用以下内容填充所有内容`A`。 

如果$k > n - 6$，这是不可能的，因为只有$n - 6$可能的起始位置。 

如果固定`C`字符与所需的模式位置不冲突`C`里面`SCNUCPC`，放置是不可能的。 例如，如果需要`S`位置已经固定为`C`，无法使用该起始索引。 

最后，重叠的模式可以相互作用，因此贪婪的布局必须避免意外地在重叠的事件之间强加矛盾。 

## 方法

 暴力视图从选择匹配的起始位置开始。 有$n - 6$可能的起始索引，我们必须准确选择$k$其中。 对于每个选定的集合，我们尝试构建一个完整的字符串：对于每个选定的开始，我们编写`SCNUCPC`进入数组，检查与现有固定的一致性`C`价值观和以前写过的信件。 放置所有选定的图案后，我们填充剩余的`?`任意并验证是否出现额外的意外匹配。 

选择位置的方法有多种$\binom{n}{k}$，即使对于中等值，也会爆炸。 每次验证都是$O(n)$，所以暴力很快就变得不可行。 

模式的结构`SCNUCPC`是关键的简化。 每个有效的出现完全由其起始索引决定，一旦我们决定将模式放置在位置$i$，所有 7 个字符都是强制的。 这表明了一种贪婪的构造：我们不是选择任意子集并检查它们，而是尝试从左到右构建答案，在本地决定是否放置模式。 

主要观察是，我们可以将其视为具有短程依赖性的约束满足问题。 每个放置仅影响大小为 7 的窗口，因此我们可以贪婪地尝试将模式放置在最早可能的有效位置，确保我们以后不会创建意外的额外匹配。 

我们模拟一个构造过程：从左到右扫描，每当我们看到将图案放置在位置$i$与现有的固定字母一致，如果我们还需要更多匹配，我们就放置它。 如果不一致，我们就跳过它。 如果我们到达终点但没有达到$k$匹配，我们知道不存在完成，因为延迟放置只会减少可用位置。 

这将问题简化为通过本地检查进行线性扫描。

 | 蛮力 |$O(\binom{n}{k} \cdot n)$|$O(n)$| 太慢了|
 | 最佳|$O(n)$每次测试|$O(n)$| 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 计算该字符串中可能包含多少个长度为 7 的子字符串。 如果$k > n - 6$,立即输出`No`。 这是一个硬组合界限，因为即使有完美的自由，也没有足够的起始位置。 
2. 处理从输入字符串初始化的可变字符数组。 保留一个柜台`need = k`代表我们还必须放置多少个图案。 
3. 扫描索引$i$从$0$到$n - 7$。 在每个位置，测试我们是否可以放置`SCNUCPC`开始于$i$。 这意味着对于每个偏移量$j$在$[0,6]$，当前单元格是`?`或者它已经匹配所需的字符。 
4. 如果安置有效并且`need > 0`，将模式写入字符串，覆盖`?`并保留现有的匹配`C`。 然后递减`need`。 我们贪婪地放置在这里的原因是，与延迟放置相比，提前放置永远不会降低未来的可行性，因为稍后的放置只会有更少的重叠选项。 
5. 扫描后，如果`need > 0`， 输出`No`。 否则，输出构造的字符串。 
6. 最后，确保不会无意中产生额外的事件。 这自然是有保证的，因为我们只放置显式模式，而不会引入在放置时未检查的部分意外完成。 

### 为什么它有效

 正确性取决于以下事实：除了重叠一致性之外，每个放置都是独立的。 当我们将图案放置在位置$i$，我们完全修复了长度为 7 的块。 任何未来的安置都必须遵守这些限制。 如果一个安置在我们考虑的那一刻是有效的，那么推迟它并不能使它在以后变得更有效，因为后来的决定只会增加约束。 因此，贪婪地在最早的有效位置提交可以保留所有可行的解决方案。 如果存在解决方案，我们可以将其转换为所有选定的起点都尽可能向左移动而不破坏有效性的解决方案，这与这种贪婪的构造相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

PAT = "SCNUCPC"
L = 7

def can_place(s, i):
    for j in range(L):
        if s[i + j] != '?' and s[i + j] != PAT[j]:
            return False
    return True

def place(s, i):
    for j in range(L):
        s[i + j] = PAT[j]

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    s = list(input().strip())

    if k > n - 6:
        print("No")
        continue

    need = k

    i = 0
    while i <= n - 7:
        if need > 0 and can_place(s, i):
            place(s, i)
            need -= 1
        i += 1

    if need > 0:
        print("No")
    else:
        print("Yes")
        print("".join(c if c != '?' else 'A' for c in s))
```该实现使用贪婪过程的直接模拟。 这`can_place`函数在不修改数组的情况下检查与模式的本地兼容性。 这`place`函数将完整模式写入数组。 

放置所有必需的事件后，剩余的`?`充满了`A`，因为它们不会贡献任何额外的有效`SCNUCPC`发生的情况，并且不能与现有的固定冲突`C`限制。 

早期绑定检查`k > n - 6`防止在不可能的情况下进行不必要的工作。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    PAT = "SCNUCPC"
    L = 7

    def can_place(s, i):
        for j in range(L):
            if s[i + j] != '?' and s[i + j] != PAT[j]:
                return False
        return True

    def place(s, i):
        for j in range(L):
            s[i + j] = PAT[j]

    t = int(input())
    out = []

    for _ in range(t):
        n, k = map(int, input().split())
        s = list(input().strip())

        if k > n - 6:
            out.append("No")
            continue

        need = k
        i = 0
        while i <= n - 7:
            if need > 0 and can_place(s, i):
                place(s, i)
                need -= 1
            i += 1

        if need > 0:
            out.append("No")
        else:
            out.append("Yes")
            out.append("".join(c if c != '?' else 'A' for c in s))

    return "\n".join(out)

 ## 边缘情况

 固定时紧边情况`C`值已经部分匹配多个重叠的候选窗口。 例如，像这样的字符串`SC?????C`可以根据对齐方式强制或禁止放置。 该算法通过从不假设字符已经固定的自由度来处理这个问题，因为`can_place`在每个位置强制执行精确的兼容性。 

另一个边缘情况是当$k = 0$。 在这种情况下，我们从不放置任何图案，只是填充所有`?`和`A`。 因为我们从来不介绍`S`，没有子串可以意外形成`SCNUCPC`，以及所有现有的`C`约束条件保持不变。 

第三种情况是最大密度，其中$k = n - 6$。 该算法将尝试放置在每个有效位置，但重叠将阻止大多数放置，除非字符串完全空闲。 这正确地拒绝了不可能的配置，因为一旦放置阻挡了邻居，未来的窗口就会变得无效并且`need`最终仍将保持积极的态度。
