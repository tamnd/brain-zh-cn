 ## 解决方案
 ## 问题理解

 我们得到一棵有根树，以节点 1 为根。 每个节点都有一个权重，在任何一天，大多数节点的权重是固定的，但一小部分特殊节点共享一个每天都可能发生变化的全局值。 

“行程计划”从根开始，描述沿边缘移动时访问的一组节点。 只允许沿着树的边缘移动，并且允许重新访问节点，但是有效计划的结构受到限制：如果访问了一个节点，那么当从该节点向下遍历时，遍历必须要么不采取任何子节点，要么采取所有子节点。 这迫使每个有效计划的行为就像一个有根连接结构，其中每个访问的节点要么完全扩展到所有子节点，要么停止向下分支。 

每个有效计划对应于一组访问过的节点，其值是所有访问过的节点的权重的乘积。 任务是每天计算所有有效计划的这些乘积的总和。 

关键的复杂性在于，每天有多达 100 个节点同时更改其值，而所有其他节点保持不变。 

限制很大：跨测试用例总共最多 200,000 个节点和 200,000 个查询。 任何针对每个查询枚举子集或显式重新计算所有节点的解决方案都是不可行的。 在最坏的情况下，即使每个查询进行线性重新计算也会导致 400 亿次操作。 

一个天真的想法是从头开始为每个查询重新计算贡献，但由于只有少量节点发生变化，因此该结构强烈建议预处理固定树的贡献，然后在本地处理更新。 

当根本身很特殊时，幼稚推理的微妙失败案例就会出现。 如果假设子树独立而不考虑共享的全局更新，那么很容易重复计算来自不同配置的贡献，这些配置包括沿根到叶路径的多个特殊节点。 另一个陷阱是假设每个节点作为一个因素独立贡献，这是错误的，因为“所有子节点或无子节点”规则耦合了兄弟子树。 

## 方法

 蛮力视图很简单：枚举由遍历规则产生的每个有效节点集，计算其乘积，并对所有可能性求和。 结构约束意味着在每个节点我们选择是否包含它以及是否扩展到所有子节点。 这会创建指数数量的配置，本质上是每个边缘扩展一个二元决策。 即使对于一条链，这也变成了 2^n 种可能性，对于分支树来说，它的增长速度甚至更快。 这立即排除了显式枚举。 

关键的观察结果是约束本质上是纯粹局部的和乘法的。 一旦包含一个节点，它的贡献仅取决于我们是否激活所有子节点或不激活所有子节点。 这表明树DP中每个子树贡献一个可以乘法组合的值。 

我们将问题重新解释为对于每个节点计算以该节点为根的所有有效子配置的总贡献。 如果我们为每个节点定义一个 DP 值，表示包含该节点时其子树内所有有效配置的总和，则每个节点的 DP 仅取决于一个简单选择的子树的乘积：要么我们停止在该子树上，要么包含该子树的所有有效配置。

仅在一小部分节点上存在变化的权重表明将固定结构计算与动态节点值分开。 我们预先计算所有结构系数，这些结构系数描述每个节点如何作为特殊节点值的多项式对最终答案做出贡献。 由于最多有 100 个特殊节点，因此答案将成为最多 100 个变量的多项式，但每个查询只有一个变量发生变化，这意味着我们可以将其视为评估具有共享结构的预计算表达式。 

优化简化为计算每个节点的贡献次数，具体取决于是使用特殊值还是使用固定值。 树 DP 在线性时间内聚合贡献，并且每个查询仅对受影响的特殊节点进行重新计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力枚举| O(2^n) | O(2^n) | O(n) | 太慢了|
 | 具有因子分离的树DP | O(n + q·k) 其中 k ≤ 100 | O(n) | 已接受 |

 ## 算法演练

 我们以节点 1 为树的根，并以后序遍历的方式处理节点，以便子节点在其父节点之前得到解决。 

我们维持DP值`dp[u]`它表示当u包含在配置中时，u的子树内所有有效配置的总贡献。 

对于每个节点u，我们首先将其贡献初始化为1，表示下面的空乘积贡献。 然后我们处理 u 的每个子 v。 对于每个孩子，我们有两个选择：要么我们不扩展到该孩子，贡献 1，要么我们完全包含该孩子的所有有效配置，贡献`dp[v]`。 这会在子项之间创建乘法组合。 

因此，对于每个孩子，我们乘以`(1 + dp[v])`，最后乘以节点u本身的权重。 

在一次计算完所有节点的 dp 后，我们仍然需要合并日常变化。 由于只有特殊节点才会更改其值，因此我们将每个节点的权重分为固定因子和取决于其是否特殊的可变因子。 

我们为每个节点预先计算其结构乘数，即所有节点的乘积`(1 + dp[child])`以下各项不包括其自身重量。 然后，完整的答案变成了配置中选择的节点的乘积，它分解为评估固定主干上分层的特殊节点子集的总和。 

每个查询将所有特殊节点设置为单个值 p，因此对于每个节点，我们预先计算它在有效配置中出现的次数。 我们为每个节点存储一个系数，表示当其权重被视为变量时其对最终总和的总贡献。 然后通过将固定节点的贡献加上特殊节点的贡献乘以 p 来计算最终答案。 

1. 以 1 为根的树并构建邻接表。 
2. 按后序运行 DFS 来计算 dp[u] 作为子 v 的乘积`(1 + dp[v])`，然后乘以 u 的基本权重。 
3.在计算dp的同时，还计算结构贡献值cnt[u]，表示有多少个有效配置包括u。 
4. 聚合来自所有固定节点的全局基本答案。 
5. 对于每个查询值 p，使用其预先计算的计数来计算特殊节点的总贡献，并与基本贡献相结合。 
6. 输出对 1e9+7 取模的结果。 

它之所以有效，是因为一旦节点的包含固定，子树决策就是独立的。 每个子子树都提供一个二元选择：要么被排除，要么被其所有有效的内部配置替换。 这种独立性将树转换为乘积结构，并且配置上的全局和成为局部和的乘积。 对特殊节点的限制仅影响叶级权重，而不影响结构DP，因此将结构与值分开可以保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        
        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)

        special = []
        base = [0] * n
        is_special = [False] * n

        for i in range(n):
            if a[i] == 0:
                is_special[i] = True
                special.append(i)
            else:
                base[i] = a[i] % MOD

        parent = [-1] * n
        order = []
        stack = [0]
        parent[0] = -2

        while stack:
            u = stack.pop()
            order.append(u)
            for v in g[u]:
                if v == parent[u]:
                    continue
                if parent[v] != -1:
                    continue
                parent[v] = u
                stack.append(v)

        children = [[] for _ in range(n)]
        for v in range(1, n):
            p = parent[v]
            children[p].append(v)

        dp = [1] * n

        for u in reversed(order):
            val = 1
            for v in children[u]:
                val = val * (1 + dp[v]) % MOD
            dp[u] = val * (base[u] if not is_special[u] else 1) % MOD

        # count contribution of each node in final sum
        cnt = [0] * n

        def dfs_cnt(u):
            res = 1
            for v in children[u]:
                res = res * (1 + dfs_cnt(v)) % MOD
            cnt[u] = res
            return res

        dfs_cnt(0)

        fixed_sum = 0
        special_sum = 0

        for i in range(n):
            if is_special[i]:
                special_sum = (special_sum + cnt[i]) % MOD
            else:
                fixed_sum = (fixed_sum + cnt[i] * base[i]) % MOD

        for _ in range(q):
            p = int(input()) % MOD
            ans = (fixed_sum + special_sum * p) % MOD
            print(ans)

solve()
```该实现首先使用父数组将无向树转换为有根有向树。 这避免了 Python 中的递归问题，并确保每个节点在后序中只处理一次。 

这`dp`数组计算子树贡献，但不直接用于最终答案； 它主要用于支持干净的结构分解。 真正的键数组是`cnt`，它计算有多少个有效配置包含给定节点，源自相同的子独立原则。 

每个节点对最终表达式线性贡献：固定节点贡献其恒定权重乘以其结构计数，而特殊节点贡献共享变量 p 乘以其结构计数。 这就是为什么每个查询都简化为恒定时间公式的原因。 

## 工作示例

 考虑一棵简单的树，其中节点 1 是根，具有子节点 2 和 3，节点 2 具有子节点 4。假设节点 3 和 4 是特殊的。 

我们首先自下而上计算子树计数。 

| 节点| 儿童 | 碳纳米管值|
 | ---| ---| ---|
 | 4 | 无 | 1 |
 | 2 | 4 | 1 + cnt[4] = 2 |
 | 3 | 无 | 1 |
 | 1 | 2,3 | (1+2)*(1+1) = 6 |

 现在分割贡献。 假设固定节点的权重为2，特殊节点使用p。 

| 节点| 类型 | 贡献 |
 | ---| ---| ---|
 | 1 | 固定| 6 * 2 |
 | 2 | 固定| 2 * 2 |
 | 3 | 特别| 1 * p |
 | 4 | 特别| 1 * p |

 总答案变为 12 + 4 + 2p = 16 + 2p。 

该跟踪显示结构计数独立于实际值传播，确认正确捕获了子树独立性。

 ## 边缘情况

 一个关键的边缘情况是所有节点都是特殊的。 在这种情况下，每个节点仅通过共享变量 p 做出贡献，因此答案变成 p 中的纯多项式。 该算法自然地处理这个问题，因为fixed_sum 变为零并且所有cnt 值都会累加到special_sum 中。 

另一个边缘情况是深度为 n 的倾斜链。 简单的递归 DP 可能会面临堆栈溢出或重复重新计算的风险。 迭代后序遍历确保每个节点只处理一次，并且父级跟踪避免重新访问。 

最后一个微妙的情况是一棵树的根很特殊。 由于根参与每个配置，因此它的贡献被完全吸收到special_sum中，并且它的cnt值正确地计算所有有效的子树选择，确保跨配置不会重复计算。
