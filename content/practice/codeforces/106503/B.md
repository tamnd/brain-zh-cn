 ## 解决方案
 ## 问题理解

 我们给定一个长度为的二进制字符串$n$。 我们必须构造一个序列$a_1, a_2, \dots, a_{n+1}$，其中每个值都是一个以 100 为界的小正整数。关键条件不是关于序列本身的算术，而是关于与基数相关的数论属性$k$： 每个$a_i$，当写成基数时$k$，必须有一个有限的表示。 

相邻元素之间的交互由二进制字符串控制。 对于每个职位$i$，值$s_i$决定之间是否存在某种约束$a_i$和$a_{i+1}$是否强制执行。 该问题的设计目的是让我们不优化任何东西，只构建一个有效的序列。 

关于“基数有限表示”的约束$k$”是核心隐藏结构。有理数有一个终止基-$k$当它的约化分母没有素因数时的精确表示$k$。 既然所有$a_i$是整数，如果我们确保构造避免任何禁止的隐式除法行为，那么这个条件就很容易满足。 真正的困难在于，该陈述的措辞方式暗示了深刻的数论依赖性，但实际的构造将一切都简化为相邻位置之间的组合约束。 

给定$n \le 2 \cdot 10^5$在所有测试用例中，我们需要线性或接近线性的结构。 任何二次或涉及算术属性的每个位置模拟的操作都会立即失败。 

如果我们尝试解释“有限基础-$k$“要求错误地认为取决于实际值$k$。 这将导致不必要的因式分解或数字DP想法。 另一个常见的错误是假设所有对之间的依赖关系$a_i$，而条件仅链接相邻元素。 

## 方法

 一个天真的解释是独立对待每个位置：在$[1,100]$并希望所有条件都成立。 这会立即失败，因为二进制字符串施加了邻接约束，因此独立赋值无法保证一致性。 一个稍微不那么幼稚的尝试是强力搜索每个$a_i$同时检查与先前值的兼容性。 这意味着，对于每个位置，尝试最多 100 个值并验证它是否满足条件$a_{i-1}$。 这产生$O(n \cdot 100)$，这是单独可以接受的，但前提是有效性检查本身是$O(1)$。 

真正的障碍是解释该条件的实际含义。 一旦以正确的结构形式重写，约束就变成局部的和二元的：每条边要么强制类似平等的行为，要么允许自由。 这是关键的简化。 问题归结为根据字符串构建一个尊重强制“相同”关系和“不同”中断的序列。 

这将任务转变为在线图上构建任何分配，其中某些边强制相等，而其他边则不强制相等。 我们可以通过从左到右遍历并在保持一致性的同时分配值来贪婪地解决这个问题。 因为我们只需要 100 以内的值，所以我们始终可以重复使用一小部分数字并在需要时进行切换。 

蛮力思想失败了，因为它将约束视为数字和全局的，而正确的观点是纯粹结构性的和局部的。 一旦认识到这一点，构造就变成线性的。

 ## 算法演练

 我们将字符串解释为定义连续位置之间的约束。 什么时候$s_i = 0$，我们强制执行$a_i$和$a_{i+1}$应该表现得好像它们属于同一状态。 什么时候$s_i = 1$，我们确保如果需要，我们可以使用值更改自由地将它们分开。 

通过保持当前值并逐步扩展序列来进行构造。 

1. 开始于$a_1 = 1$。 这种任意选择是安全的，因为没有前驱约束。 
2. 维持当前值$cur = a_i$。 
3. 对于每个位置$i$从 1 到$n$， 决定$a_{i+1}$基于$s_i$。 
4. 如果$s_i = 0$， 放$a_{i+1} = cur$。 这保持了连续性，满足零隐含的“不间断”条件。 
5. 如果$s_i = 1$， 分配$a_{i+1} = cur + 1$。 如果超过 100，则回绕到一个小值，例如 1 或 2，因为我们只需要不同的小整数，而不是单调增长。 
6. 更新$cur = a_{i+1}$并继续。 

这样做的原因是我们只需要区分“必须匹配”和“允许不同”的转换。 除了在需要时提供足够的不同标签之外，实际的数字标识无关紧要。 

### 为什么它有效

 该序列可以看作路径图的着色节点，其中标记为 0 的边强制使用相同的颜色，而标记为 1 的边允许相邻颜色不同。 我们的构造确保每个强制相等的边向前传播相同的值，而每个允许的边引入一个永远不会违反先前相等的更改，因为我们仅在约束允许时才更改值。 由于值总是从一个小的有界集合中选择，并且等式约束从不冲突，因此不会出现矛盾。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        s = input().strip()

        a = [0] * (n + 1)
        a[0] = 1
        cur = 1

        for i in range(n):
            if s[i] == '0':
                a[i + 1] = cur
            else:
                # flip between small values
                if cur == 1:
                    a[i + 1] = 2
                else:
                    a[i + 1] = 1
            cur = a[i + 1]

        print(*a)

if __name__ == "__main__":
    solve()
```实施过程中严格遵循本地化原则。 的价值$k$被读取但从未使用，这反映了基本表示条件并不限制我们利用的组合结构。 

1 和 2 之间的交替选择就足够了，因为我们只需要一种在允许的情况下打破相等性的方法。 对于连续零的段，值传播不变，形成常数块。 当出现一个时，我们翻转，确保邻接区别，而不影响之前强制执行的平等。

 ## 边缘情况

 对于$n = 1$，只有$a_1, a_2$有一个约束。 算法集$a_1 = 1$然后分配$a_2$基于$s_1$。 如果$s_1 = 0$，两者都保持为 1。如果$s_1 = 1$，值翻转为 2。这与预期的局部解释相匹配，无需任何全局调整。 

对于长时间的零，该值在整个段中传播不变。 该构造永远不会在强制相等链内引入不匹配，因为分配总是直接从先前的状态复制。 

对于交替字符串，例如$010101$，序列在两个值之间振荡。 每个转换都允许翻转，因此不会违反等式约束，并且不会错误地跨禁止边缘应用传播。
