 ## 解决方案
 ## 问题理解

 我们正在构建长度序列`n`使用`m`不同的标签编号为`0`到`m-1`，限制是序列内没有重复的标签。 所以每个有效序列本质上是一个有序的选择`n`不同的元素来自`m`，即大小的排列`n`取自`m`。 

对于每个这样的序列，我们查看每个前缀。 对于前缀，我们计算它的 mex，它是未出现在该前缀中的最小非负整数。 然后，我们将所有前缀长度上的这些 mex 值相加`1`到`n`，并将其称为序列的分数。 任务是计算所有有效序列的分数总和。 

限制条件很大：`n`达到一百万，并且`m`高达十亿。 这立即排除了任何迭代排列甚至处理与`m`。 解决方案必须仅依赖于`n`并避免接触全范围`[0, m)`明确地。 任何平方项`n`也是不安全的，因此最终表达式必须在代数简化后简化为线性或近线性计算。 

一个常见的失败案例来自直接尝试跨排列模拟 mex。 即使对于像这样的小例子`n = 3, m = 5`，野蛮一代已经产生`P(5,3) = 60`序列，并且计算每个前缀的 mex 仅适用于玩具输入。 扩展这个想法会立即失败。 

另一个微妙的边缘情况是误解标签来自`0`到`m-1`。 一些天真的解释假设我们只使用`0..n-1`，但这里未使用的较大值很重要，因为它们会影响小数字在排列早期出现的频率，从而直接影响 mex 增长。 

## 方法

 暴力方法将生成每个有效的长度排列`n`从`m`元素。 对于每个排列，我们通过扫描来计算每个前缀的 mex`0`向上直到找到缺失值。 即使使用哈希集优化每个前缀的 mex，我们仍然至少支付`O(n)`每个排列，并且有`P(m, n)`排列。 即使对于小型企业来说，这也是天文数字般的增长`n`，所以该方法不可行。 

关键的结构观察是 mex 仅取决于前缀中出现的小值，而不取决于它们超出存在的顺序。 前缀处的 mex 至少为`k`恰好当所有值`0..k-1`存在于该前缀中。 这让我们可以将 mex 重新表述为指标事件的总和。 

我们重写了前缀贡献，这样我们就可以计算每个阈值的次数，而不是直接计算 mex`k`在所有排列的前缀内部都“完全满足”。 这将非线性函数转换为简单组合条件下的总和。 

一旦我们确定了一个值`k`，条件变为：前缀包含所有元素`0..k-1`。 其余的计算简化为计算排列如何在前缀之间分配这些特殊元素，这成为一个组合放置问题。 简化后，阶乘恒等式将表达式折叠为二项式系数和附近连续数值范围的乘积`m`，可以使用前缀产品来处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数为`n`和`m`| O(n) | 太慢了|
 | 组合重写| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们将墨西哥总和转换为阈值的贡献`k`， 在哪里`k`代表所有值的事件`0..k-1`已经存在于前缀中。 

1. 我们将前缀的 mex 表示为指标之和`k`，其中`k`- 如果前缀包含所有数字，则第一个指示符为真`0..k-1`。 这将总答案转换为总和`k`满足该条件的前缀配置的计数。 
2.对于固定的`k`，我们计算长度的前缀有多少种方式`i`包含所有元素`0..k-1`，而完整序列仍然是长度的有效排列`n`。 
3. 我们选择前缀中的哪些位置包含这些`k`特殊元素，然后用任意剩余元素填充剩余的前缀和后缀。 这导致了阶乘式项的乘积。 
4. 简化组合后，对字母大小的依赖`m`干净地分解为仅涉及连续整数段上的乘积的因子，而组合前缀结构仅取决于二项式系数。 
5. 然后，我们使用已知恒等式对所有前缀长度隐式求和：沿对角线的二项式系数之和折叠为单个二项式系数，从而删除求和的一个维度。 
6. 最终表达式变成一个单一的总和`k`从`1`到`n`，其中每一项都是三部分的乘积：阶乘项取决于`k`，二项式系数仅取决于`n`，以及前缀乘积比率取决于`m`和`n`。 
7. 我们预先计算阶乘和逆阶乘`n+1`对于二项式系数，我们在表示范围的移位数组上预先计算前缀乘积`[m-n+1, m]`评估每项 O(1) 中的大量乘积比率。 

### 为什么它有效

 正确性来自两个不变量。 首先，mex 分解确保每个前缀在每个阈值中准确贡献一次`k`完全满足，因此不会发生过度计算。 其次，组合计数处理第一个的所有位置`k`各个排列之间的数字对称，确保每个有效的排列配置对于每个相关的前缀长度都精确计数一次。 代数约简保留了这些计数，同时消除了对排列结构的显式依赖。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

n, m = map(int, input().split())

# factorials for binomial coefficients up to n+1
fact = [1] * (n + 3)
invfact = [1] * (n + 3)

for i in range(1, n + 3):
    fact[i] = fact[i - 1] * i % MOD

invfact[n + 2] = modinv(fact[n + 2])
for i in range(n + 2, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def C(a, b):
    if b < 0 or b > a:
        return 0
    return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

# build product over [m-n+1 .. m]
start = m - n + 1
prod = [1] * (n + 1)

for i in range(n):
    prod[i + 1] = prod[i] * (start + i) % MOD

def range_prod_inv(l, r):
    # product of A[l..r]
    val = prod[r + 1] * modinv(prod[l]) % MOD
    return modinv(val)

ans = 0

for k in range(1, n + 1):
    comb = C(n + 1, k + 1)
    coeff = fact[k]
    
    # product over (m-n+1 .. m-k)
    l = 0
    r = n - k - 1
    if l <= r:
        ratio = range_prod_inv(l, r)
    else:
        ratio = 1
    
    ans = (ans + coeff * comb % MOD * ratio) % MOD

print(ans)
```该实现将解决方案分为三个独立的组件。 仅二项式项需要阶乘表`C(n+1, k+1)`。 价值大`m`仅出现在单个连续产品范围内，因此我们在该间隔上构建一个前缀产品数组`[m-n+1, m]`。 这可以避免迭代到`m`，这是不可能的。 

功能`range_prod_inv`使用前缀积和模逆返回子段积的逆。 这是必要的，因为导出的公式需要除以连续整数的乘积。 

主循环迭代`k`，独立累加每个贡献，这是安全的，因为在代数简化之后每一项已经完全分离。

这个例子显示了有多高`k`价值观自然会变得更加稀有，但个体更加结构化。

 ## 边缘情况

 当`n = 1`，每个序列都由一个元素组成，并且 mex 始终是`0`或者`1`取决于该元素是否是`0`。 该算法可以正确处理这个问题，因为只有`k = 1`术语存在并干净地减少为单个前缀上的简单组合计数。 

什么时候`n = m`，所有元素都只使用一次。 在这种情况下，产品范围超过`[m-n+1, m]`成为一个完整的连续块，开始于`1`，并且前缀乘积反转仍然有效，因为不会发生被零除的情况。 组合项仍然有效，因为每个排列都是集合的完整排列。 

什么时候`m`远大于`n`，依赖于`m`折叠成一个短的产品段，算法仍然以线性时间运行`n`无需明确触及大值，确保最大约束下的稳定性。
