 ## 解决方案
 ## 问题理解

 我们有两个整数，代表两个以不同值开始的计数器。 在一次移动中，我们可以将第一个计数器增加 1 或将第二个计数器增加 2。任务是确定所需的此类移动的最小数量，以便在某个时刻两个计数器变得相等。 

关键在于，在这个过程中不需要保持相等性，只需要存在一系列操作使两个值在最后相等即可。 

约束允许值高达$10^9$，这立即排除了对状态的任何模拟或对可能序列的穷举搜索。 每个测试用例的任何解决方案都必须以恒定或对数时间运行。 由于每个操作仅增加值，因此该结构是单调的，并且强烈建议直接推理差异和奇偶性，而不是构造序列。 

奇偶校验不匹配会产生微妙的边缘情况。 由于一个操作增加 1，另一个操作增加 2，因此 x 和 y 之间的相对差异以受约束的方式变化。 例如，如果 x 一开始比 y 大得多，反之亦然，总是试图在本地“缩小差距”的天真贪婪方法可能会失败，因为它忽略了 y 只能以 2 为步长递增。 

另一种边缘情况是 x 已经比 y 大奇数。 例如，x = 3，y = 0。“匹配增量”的天真尝试可能会假设我们始终可以对齐它们，但奇偶校验限制可能会强制执行额外的绕道步骤。 

## 方法

 暴力解决方案将尝试所有可能的操作序列直至达到一定限度，模拟每一步的两种选择并检查何时首次实现相等。 这形成了一个二元分支过程，其中每一步都会增加 x 或 y，并且搜索空间随着移动次数呈指数增长。 即使差异很小，状态的数量也会激增，使得这种方法在输入非常小的情况下不可行。 

关键的观察结果是，只有 x 和 y 之间的差异很重要，并且每个操作都会以可预测的方式改变这种差异。 如果我们定义差异$d = y - x$，然后增加 x 会使 d 减少 1，而增加 y 会使 d 增加 2。目标是达到这样的状态：$d = 0$。 

这将问题转化为使用 -1 和 +2 步长从初始整数达到零。 这是整数上的经典可达性问题，但更重要的是，很明显我们可以推理奇偶校验和最佳平衡，而不是模拟序列。 

最佳策略取决于我们是否想要增加或减少间隙，以及奇偶校验是否允许精确对齐。 核心思想是选择多个+2运算（在y上），然后使用+1运算（在x上）进行补偿，使两个值完全满足。 这导致直接算术解决方案而不是动态过程。

 ## 算法演练

 我们首先将该过程解释为使用两种类型的增量来平衡两个数字。 

1. 计算差异$d = y - x$。 这衡量了价值观之间的差距，并告诉我们哪一方需要更多的增长才能满足另一方的需求。 这种差异的符号决定了当前哪个变量落后。 
2.如果$d = 0$，数字已经相等，无需进行任何操作。 答案立即为零。 
3.如果$d > 0$，那么 y 领先于 x，我们需要更积极地增加 x。 由于x只能增加1，而y增加2，所以我们不能直接减少y。 相反，我们必须依靠 x 赶上，同时可能允许 y 继续以受控量增加。 
4. 要对此进行建模，请考虑对 y 执行 k 次操作，对 x 执行 t 次操作。 经过这些操作后，值变为$x + t$和$y + 2k$。 我们要求平等，所以$x + t = y + 2k$，重新排列为$t - 2k = d$。 我们想要最小化$t + k$受此约束。 
5. 根据等式，我们表示$t = d + 2k$，因此总操作变为$t + k = d + 3k$。 最小化该表达式可以简化为选择使构造有效的最小可行 k。 由于所有值都保持非负数，并且运算没有上限，因此当 d 非负数时，最佳选择是 k = 0，从而导致 t = d。 
6.如果$d < 0$，则 x 领先于 y。 对称地，我们必须考虑使用 +2 运算来增加 y 并用 x 增量进行补偿。 约束变为$x + t = y + 2k$，现在 y 必须赶上，所以我们依靠 k 来控制差异。 最小解是通过选择 k 使得奇偶校验对齐而产生的，这意味着$y + 2k$可以以最小的额外 x 增量达到或超过 x。 
7. 最终答案简化为绝对差的奇偶调整上限除法，反映出 y 上的每个 +2 操作必须通过 x 上的 +1 操作来平衡，并且不匹配的奇偶校验会强制进行一次额外的操作。 

### 为什么它有效

 该过程完全由单个差分变量的线性变换确定。 每个操作都以固定的方式改变差异，因此系统除了奇偶性和幅度之外没有隐藏状态。 任何最佳序列都可以重新排列，以便将 y 上的所有 +2 操作分组，然后补偿 x 上的 +1 操作，而不影响可行性。 这种交换性意味着只有运算次数才重要，而不是顺序，并且最小解简化为求解具有奇偶校验约束的整数上的线性方程。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())
    
    # Let x and y be transformed toward equality.
    # We reason directly about the difference.
    if x == y:
        print(0)
        return
    
    # We test both possibilities implicitly via arithmetic reasoning.
    # The key derived result is that the answer depends on how far apart they are
    # and the fact that y grows in steps of 2 while x grows in steps of 1.
    
    if x > y:
        diff = x - y
        # y must catch up in steps of +2, x can also move.
        # optimal is to balance parity: we need enough +2 steps so that parity matches.
        print((diff + 1) // 2 + diff % 2)
    else:
        diff = y - x
        # x can only increase by 1, so we directly match or overshoot y.
        print(diff // 2 + diff % 2)

if __name__ == "__main__":
    solve()
```该解决方案根据较大的数字来区分这两种情况。 这是必要的，因为只有 x 或 y 具有很强的奇偶约束增量，并且限制方改变了最优策略的结构。 

当 x > y 时，主要约束是 y 只能以 2 的步长移动，因此匹配奇偶校验可能需要额外的补偿移动。 表达式`(diff + 1) // 2 + diff % 2`编码两步调整的最小数量加上奇偶校验不匹配时的校正。 

当 y > x 时，x 总能以单位步缩小差距，但当差异较大且均匀时，使用 y 的 +2 步可以减少运算次数。 公式`diff // 2 + diff % 2`抓住了这种权衡。 

## 工作示例

 我们追踪两个代表性案例，看看奇偶性如何影响结果。 

### 示例 1：x = 5，y = 10

 | 步骤| x| y | 差异 (y-x) | 动作解读|
 | --- | --- | --- | --- | --- |
 | 0 | 5 | 10 | 10 5 | 初始状态|

 这里 y 领先 5。我们应用 y > x 的公式：`diff // 2 + diff % 2 = 5 // 2 + 1 = 2 + 1 = 3`。 

这对应于在 y 逻辑上使用两次 +2 操作（从概念上减少所需的追赶结构），再加上一个最终调整步骤。 轨迹显示，除了纯粹的减半之外，奇怪的间隙会迫使进行额外的操作。 

### 示例 2：x = 9，y = 3

 | 步骤| x| y | 差异 (x-y) | 动作解读|
 | --- | --- | --- | --- | --- |
 | 0 | 9 | 3 | 6 | 初始状态|

 现在 x 领先 6。我们使用 x > y 公式：`(diff + 1) // 2 + diff % 2 = (6 + 1)//2 + 0 = 3`。 

这表明，当差异为偶数时，运算完全配对，并且不需要奇偶校验校正。

 ## 边缘情况

 当 x 和 y 最初相等时，算法立即返回零，而不进入任何算术分支。 这避免了不必要的奇偶校验推理并确保了平凡不动点的正确性。 

当差值恰好为 1 时，例如 x = 0、y = 1，算法通过强制执行额外的补偿操作来正确处理奇数间隙。 该表达式确保单个不匹配无法单独通过 +2 步骤解决，因此结果变为 1 而不是 0。 

当差异较大且均匀时，例如 x = 10^9 且 y = 0，解决方案对会干净利落地递增，并在操作中产生正好一半的距离，反映了 +2 步移动的最佳配对，而没有浪费调整。
