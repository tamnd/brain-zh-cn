 ## 解决方案
 ## 问题理解

 我们从一个盒子内单位立方体的矩形 3D 排列开始，盒子的尺寸为$n \times m \times h$。 各位置$(i, j)$在一个$n \times m$网格描述了具有高度的垂直立方体堆叠$A_{i,j}$。 所以最初的结构是平面图上的高度图。 

然后旋转盒子，这样以前垂直堆叠的东西现在可以从不同的侧面看到。 旋转后，我们再次将可见结构描述为网格，这次的大小$h \times m$，其中每个单元格$B_{i,j}$表示重力作用于新方向后该位置可见的立方体数量。 

关键是立方体不会随意移动。 旋转后它们在重力作用下沿新的垂直方向下落，因此新视图中的每一列都是通过堆叠“投影”到该列上的所有立方体形成的，并按旋转后的高度排序。 

思考这个问题的一个有用方法是每个原始列$(i,j)$贡献了垂直的一堆$A_{i,j}$立方体。 旋转后，这些堆在不同的轴上重新排列，重力将它们压实成新的柱。 

限制条件$n, m, h \le 100$表明任何$O(nmh)$甚至小型恒定因子 3D 模拟也是可以接受的。 排除的是每个立方体的任何组合模拟，重复扫描大区域或对每个单元执行重复重新堆叠。 

一个微妙的边缘情况是当许多堆栈为零或所有堆栈都最大时。 天真的“直接旋转和分配”方法往往会假设一个简单的转置式映射，但由于重力改​​变了最终分布，这种映射会失败。 例如，如果所有$A_{i,j} = 1$，结果不是一个简单的排列； 相反，堆叠会导致沿着新的垂直轴进行整合。 

## 方法

 直接模拟将独立处理每个立方体。 对于每个细胞$(i,j)$，我们可以生成$A_{i,j}$单位立方体并模拟它们旋转后的运动。 每个立方体都将通过坐标变换进行跟踪，然后在重力作用下掉落直至稳定下来。 这在概念上是正确的，但在计算上却会爆炸。 在最坏的情况下，最多有$n \cdot m \cdot h = 10^6$立方体，每个立方体可能需要扫描一列大小$h$，大致导致$10^8$操作或更多。 

关键的观察是我们永远不需要模拟单个立方体。 旋转后，重要的只是有多少立方体到达每个投影柱。 一旦我们知道了对某个位置有贡献的多组柱高，重力就会简单地将它们按顺序堆叠起来。 因此，问题简化为将原始网格中的值收集到由新方向索引的桶中，然后对每个桶执行稳定的垂直打包。 

具体来说，每个原始列贡献其高度$A_{i,j}$到旋转网格中的某个位置。 旋转映射索引，以便第一个坐标成为新系统中的高度，同时保留第二个坐标。 这引起了分组：对于每个固定$j$，我们收集所有$A_{i,j}$穿过$i$，然后模拟将它们堆叠成$h$- 高柱。 

我们不是在物理上模拟重力，而是简单地独立解释每一列：对于每个$j$，我们处理列表$[A_{1,j}, A_{2,j}, \dots, A_{n,j}]$作为一组要放入高度垂直的容器中的块$h$。 每个街区从下到上贡献占用率。 

这减少了填充问题$m$高度独立的列$h$，每个都由一列中的多组值构造而成$A$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（每个立方体模拟）|$O(nmh)$到$O(nmh \cdot h)$|$O(nmh)$| 太慢了|
 | 列聚合|$O(nmh)$|$O(mh)$| 已接受 |

 ## 算法演练

 我们将问题重新解释为构建$m$输出网格中独立的垂直列，每个高度$h$，通过叠加输入矩阵的贡献而形成。 

1.对于每个列索引$j$,收集所有值$A_{i,j}$为了$i = 1 \ldots n$。 这表示所有堆栈在旋转视图中与相同的水平位置对齐。 我们按列分组的原因是旋转在交换垂直结构的同时保留了水平对齐。 
2.对于每组对应的列$j$，我们通过在填充大小数组的同时以任意顺序处理值来模拟新方向的重力$h$从下到上。 我们维护一个指示下一个可用高度位置的指针。 
3. 对于每个值$x = A_{i,j}$，我们放置$x$单位立方体从列中当前最低可用位置开始，向上移动。 每次放置都会增加指针。 如果列已满，多余的部分将被忽略。 
4. 重复直到列中的所有值$j$被处理。 这会产生输出网格的一整列。 
5. 将结果列存储到答案矩阵中$B$。 

一个关键细节是我们不需要模拟单个立方体位置。 我们只需要知道堆叠后每列填充了多少个单元格即可。 

### 为什么它有效

 正确性依赖于这样一个事实：旋转后，每个输入堆栈贡献相同单位立方体的连续垂直段。 新方向的重力不会将来自不同堆栈的立方体交错； 它仅按到达顺序对这些航段进行排序。 由于所有多维数据集都是相同的，只有它们的数量很重要，因此最终结构仅取决于分配给每列的多维数据集数量，而不取决于它们的内部顺序。 因此，独立处理每一列并从下到上贪婪地堆叠会产生与完整物理模拟完全相同的占用率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m, h = map(int, input().split())
A = [list(map(int, input().split())) for _ in range(n)]

B = [[0] * m for _ in range(h)]

for j in range(m):
    col = []
    for i in range(n):
        if A[i][j] > 0:
            col.append(A[i][j])

    ptr = 0
    for x in col:
        for _ in range(x):
            if ptr < h:
                B[ptr][j] = 1
                ptr += 1

for i in range(h):
    print(*B[i])
```该实现直接遵循算法的以列为中心的视图。 我们独立构建每一列，然后通过从下到上填充指针来模拟堆叠。 内部循环将每个高度值扩展为单位贡献，考虑到总立方体的约束，这是安全的$10^6$。 

一个微妙的点是绑定检查`ptr < h`。 如果没有它，溢出的列会因写入超出预期高度而在逻辑上破坏相邻内存。 由于旋转后多余的立方体在物理上位于可见区域之外，因此它们会被安全地丢弃。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m, h = map(int, input().split())
    A = [list(map(int, input().split())) for _ in range(n)]

        col = []
        for i in range(n):
            if A[i][j] > 0:

        ptr = 0
        for x in col:

                if ptr < h:
                    B[ptr][j] = 1
                    ptr += 1

    return "\n".join(" ".join(map(str, row)) for row in B) + "\n"

 ## 边缘情况

 一个关键的边缘情况是当单列产生的立方体多于高度时$h$。 该算法通过在以下情况时停止写入来处理此问题：`ptr == h`。 例如，如果$h = 3$和一个专栏贡献$5$立方体，只放置前三个。 其余的立方体将被忽略，因为它们在重力压缩后位于可见高度之外。 

另一种情况是列中的所有条目均为零。 列列表变为空，因此指针永远不会移动，并且输出列完全为零。 这符合垂直切片中不存在立方体的物理解释。 

第三种情况是统一的非零输入，其中每个$A_{i,j} = 1$。 各栏目贡献$n$单个立方体，并且堆叠简单地从下到上填充$h$。 该算法正确压缩所有贡献，而不依赖其顺序，从而确认输入行的排列不会影响结果。
