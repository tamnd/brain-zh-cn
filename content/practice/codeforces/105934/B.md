 ## 解决方案
 ## 问题理解

 这些城市有序地坐落在一条河上。 寻宝者从城市 1 开始。到达城市`i + 1`从城市`i`成本`c_i`硬币，并且没有替代路线。 

每个城市都包含一个宝箱价值`a_i`硬币。 猎人最多拥有`k`钥匙，所以在整个探险过程中他们最多可以打开`k`胸部。 即使他们访问了任何城市，他们也可能会跳过它。 

在某个时刻，他们决定停止探索。 返回下游是免费的，因此唯一的旅行成本是到达最远的访问城市所支付的费用。 

对于每个可能的停靠城市，我们必须确定最佳利润：`coins collected from opened chests - travel costs paid`并输出最大可实现值。 

约束条件很大，最多`10^5`城市，而宝藏价值和旅行费用可达`10^9`。 任何重复扫描前缀或重复对大范围进行排序的解决方案都会太慢。 一个`O(n^2)`方法需要围绕`10^10`在最坏的情况下进行操作，这是完全不可行的。 我们需要一些接近的东西`O(n log n)`。 

一个微妙的点是打开箱子是可选的。 认为：```
n = 3, k = 2
a = [100, 1, 1]
```最佳选择是仅打开已访问前缀中可用的有价值的箱子。 如果同一个可达集合中存在较大的箱子，我们绝对不想在较小的箱子上浪费钥匙。 

另一个容易犯的错误是认为目的地城市必须有一个打开的箱子。```
n = 3, k = 1
a = [100, 1, 1000]
c = [10, 10000]
```在城市 2 停留可获得利润`100 - 10 = 90`。 前往城市 3 是灾难性的，因为额外的旅行费用超过了额外的宝藏。 停止点和打开的箱子是独立决定的。 

当少于`k`已访问过的城市。```
n = 2, k = 2
a = [5, 7]
c = [1]
```到达城市 1 后，最好的收藏宝藏是`5`，而不是“两件宝物的总和”。 该算法必须自然地处理长度小于的前缀`k`。 

## 方法

 暴力解决方案考虑每个停止的城市`i`。 

如果我们停在城市`i`, 仅城市`1...i`是可达的。 在这些城市中，最好的策略是显而易见的：打开价值最大的宝箱，最多`k`其中。 旅行费用是固定的，等于：```
c1 + c2 + ... + c(i-1)
```所以我们可以计算：```
profit(i) =
(sum of k largest values in a[1..i])
-
(prefix travel cost)
```暴力执行将重新计算`k`每个前缀的最大值独立。 对每个前缀成本进行排序`O(i log i)`，大致导致`O(n^2 log n)`全面的。 和`n = 10^5`，这太慢了。 

关键的观察结果是前缀一次会增长一个城市。 当城市`i`添加后，仅考虑一项新的宝藏价值。 我们不需要重新计算整个top集合`k`从头开始的宝藏。 

维持目前的`k`迄今为止发现的最大的宝藏价值。 最小堆非常适合于此。 该堆准确地存储了当前选择打开的宝藏。 它的尺寸永远不会超过`k`。 

当新的宝藏到达时：

 如果堆包含的内容少于`k`元素，我们必须包含它。 

否则，将其与位于最小堆顶部的最小选定宝藏进行比较。 如果新值较大，则替换最小的所选宝藏会增加所选宝藏的总和。 如果不是更大，则选择的最佳宝藏集保持不变。 

这给出了最大的总和`k`每个前缀中的值`O(log k)`每个城市的时间。 

出行费用就更简单了。 让`cost`是到达当前城市所支付的累计费用。 当我们离开城市时`i`到城市`i + 1`， 添加`c_i`。 

对于每个前缀，我们计算：```
current_profit = sum_top_k - cost
```并保持最大值。 

官方的观察是，如果猎人停在城市里`i`，最佳利润等于`k`前缀中最大的宝藏价值`a[1..i]`减去到达该城市所需的旅行费用。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n² log n) | O(n² log n) | O(n) | 太慢了|
 | 最佳 | O(n log k) | O(n log k) | O(k) | 已接受 |

 ## 算法演练

 1. 阅读`n`,`k`, 宝藏价值`a`，以及旅行费用`c`。 
2. 创建一个空的最小堆和一个变量`selected_sum = 0`。 
3. 维护`travel_cost`，到达当前城市所支付的总费用。 
4. 从左到右处理城市。 
5.对于目前的宝藏价值`a[i]`，更新选定的宝藏堆。 

如果堆大小小于`k`，压入该值并将其添加到`selected_sum`。 
6. 如果堆已经包含`k`元素，比较`a[i]`用最小的选择宝藏。 

如果`a[i]`较大，取出最小的选定宝物，插入`a[i]`，并更新`selected_sum`因此。 
7. 更新堆后，`selected_sum`等于最大的总和`k`当前前缀中的宝藏值。 
8. 计算：```
profit = selected_sum - travel_cost
```用迄今为止看到的最大利润更新答案。 
9. 在前往下一个城市之前，将相应的旅行费用添加到`travel_cost`。 
10.所有城市处理完毕后，打印最大利润。 

### 为什么它有效

 对于任何停留城市`i`，可达城市正是前缀`1...i`。 在这些城市中，任何最佳策略都会打开最有价值的可用宝箱，最多可达`k`其中。 选择较小的宝箱而跳过较大的可触及宝箱只会降低利润。 

堆不变量是它总是存储最大的`k`迄今为止处理的所有城市中的宝藏价值。 每当一个新的宝藏进入前缀时，对最佳集合的唯一可能的改变就是替换当前选择的最小的宝藏。 堆正是执行此更新。 

自从`selected_sum`总是等于最大的数之和`k`当前前缀中的宝藏，以及`travel_cost`等于到达该前缀的最后一个城市所需的成本，计算出的利润正是该停止点的最佳利润。 取所有停止点的最大值即可得到全局最优值。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    c = []
    if n > 1:
        c = list(map(int, input().split()))
    
    heap = []
    selected_sum = 0
    travel_cost = 0
    answer = 0

    for i in range(n):
        x = a[i]

        if len(heap) < k:
            heapq.heappush(heap, x)
            selected_sum += x
        elif x > heap[0]:
            removed = heapq.heapreplace(heap, x)
            selected_sum += x - removed

        answer = max(answer, selected_sum - travel_cost)

        if i < n - 1:
            travel_cost += c[i]

    print(answer)

solve()
```堆存储当前选择的宝藏。 因为它是一个最小堆，所以选择的最小的宝藏总是可用的`O(1)`时间。 

当堆大小低于`k`，每一个新的宝藏都自动属于当前的顶级-`k`放。 一旦堆达到大小`k`，只有当新宝藏大于所选的最小宝藏时，它才重要。`selected_sum`是增量更新的。 每次迭代重新计算堆的总和会将解决方案变成`O(nk)`。 

操作顺序很重要。 为城市带来的利润`i`必须在添加前往城市的交通费用之前计算`i + 1`。 那一刻，`travel_cost`应准确代表到达城市所花费的金额`i`。 

所有算术都使用 Python 整数，它可以安全地处理远大于最大可能答案的值。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log k) | O(n log k) | 每个城市最多执行一次堆操作 |
 | 空间| O(k) | 堆最多存储`k`宝藏|

 和`n ≤ 10^5`,`O(n log k)`轻松符合典型的竞争性编程限制。 内存使用量很小，因为只有选定的宝藏保存在堆中。

 ## 边缘情况

 考虑一下长途旅行有害的情况。```
3 1
100 1 1000
10 10000
```在城市 1，堆包含`{100}`利润是`100`。 在2号城，最好的宝藏仍然是`100`，但利润下降到`90`因为旅行费用。 在城市 3，堆变为`{1000}`，但利润变为`1000 - 10010`，这是负数。 算法正确地保留了最大值`100`。 

现在考虑一个短于`k`。```
2 2
5 7
1
```在城市 1 之后，堆中仅包含一件宝藏，并且`selected_sum = 5`。 该算法从不准确地假设`k`宝藏一定存在。 在城市 2 之后，堆里包含了两种宝藏，答案就变成了`12 - 1 = 11`。 

最后，考虑重复值。```
4 2
5 5 5 5
1 1 1
```堆总是存储两个值的副本`5`。 相同的值不会触发不必要的替换，因为替换选定的值`5`与另一个`5`没有任何改变。 堆包含最大的不变量`k`值在整个执行过程中保持有效。
