 ## 解决方案
 ## 问题理解

 我们得到了一个隐藏的大小排列$n$，但我们从来没有直接看到它。 相反，我们看到该排列中每个连续的三个元素块。 然后，每个块都会在内部进行加扰，并且所有块都会相互打乱。 

所以输入是一个多重集$n-2$无序三元组。 每个三元组最初来自同一排列中的三个连续位置，但每个三元组内部的顺序和三元组的顺序都丢失了。 

任务是重建可能精确产生这个三元组集合的任何排列。 

约束条件$n \le 10^5$意味着我们不能尝试测试候选排列或使用指数重建。 我们本质上需要线性或接近线性的行为，因为像这样的东西$O(n \log n)$或者$O(n)$是可以接受的，但对或排列的二次推理则不行。 

一个微妙的点是所有值都是不同的，因此每个数字恰好对应于隐藏排列中的一个位置。 这将问题变成了邻接约束的重建任务，而不是多集模糊性。 

如果我们假设每个三元组都是有序的，则会出现一种故障模式。 例如，将三元组视为固定顺序会错误地强制不存在的邻接关系。 另一种失败模式是在不识别端点的情况下尝试贪婪地缝合三元组，这可能会导致链中间出现矛盾。 由于三元组在原始结构中恰好有两个元素重叠，但我们失去了顺序，因此简单的合并很容易产生错误的分支。 

## 方法

 一个直接的暴力想法是将每个三元组视为一个可能的有序序列，并尝试通过回溯来重建排列。 对于每个三元组，我们可以选择一个排序并尝试将其与其他三元组按顺序放置，检查重叠的一致性。 由于每个三元组都有$3! = 6$内部订单有$n-2$三元组，这创造了巨大的搜索空间。 即使忽略三元组的排列，这也会导致$6^{n}$最坏的情况下的可能性，这是完全不可行的。 

关键的观察结果是，尽管顺序丢失了，但邻接信息仍然隐式保留。 在原始排列中，每个内部元素恰好出现在两个三元组中，而端点仅出现在一个三元组中。 这意味着我们可以通过频率计数来恢复端点：仅出现一次的两个数字是排列的末端。 

一旦我们修复了端点，就可以通过重复扩展链来重建其余的排列。 关键的结构事实是每个三元组编码一个长度为 3 的滑动窗口，因此任何有效的重建必须满足每个连续对至少一起出现在一个三元组中。 这将问题简化为沿着由局部约束定义的路径行走，其中已使用的元素消除了歧义。 

蛮力和这种方法之间的区别在于，我们用由度约束和局部一致性驱动的确定性图式重建来替换三元组的组合排序。

 ## 算法演练

 我们将问题转化为跟踪哪些值出现在哪些三元组中以及它们出现的频率。 

1. 计算每个数字在所有三元组中出现的次数。 这标识了端点，因为内部元素恰好出现在两个三元组中，而端点出现一次。 这是有效的，因为每个内部位置都对两个滑动窗口有贡献。 
2. 识别频率为 1 的两个数字。它们必须是排列的第一个和最后一个元素，尽管它们的顺序尚不清楚。 
3. 选择一个端点作为起点。 从这一点开始，我们将从左到右重建排列。 
4. 预处理：对于每个数字，存储包含它的三元组。 这使我们能够在扩展序列时快速找到候选三元组。 
5. 逐步构建排列。 从第一个端点开始，使用包含当前对上下文的三元组重复查找下一个数字。 具体来说，一旦我们有两个连续的数字，下一个元素必须是包含这两个数字的任何三元组中的第三个元素。 
6. 在每一步中，从匹配的三元组中选择未使用的元素。 由于该结构保证形成有效的链，因此将存在一个未使用的候选者。 
7. 继续，直到所有$n$元素被放置。 

重建本质上是走一条独特的路径，其中每一步都是由长度为 3 的窗口的重叠约束确定的。 

### 为什么它有效

 排列中的每个内部元素恰好属于两个连续的三元组，而端点属于一个。 这迫使三元组的隐式超图中出现类似路径的结构。 一旦端点固定，每一对连续元素就唯一地确定下一个元素，因为只有一个三元组可以一致地扩展当前窗口而不违反频率限制。 这可以防止分支并保证一次一致的遍历，一次覆盖所有元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    triples = []
    
    freq = [0] * (n + 1)
    where = [[] for _ in range(n + 1)]
    
    for i in range(n - 2):
        a, b, c = map(int, input().split())
        triples.append((a, b, c))
        for x in (a, b, c):
            freq[x] += 1
            where[x].append(i)
    
    ends = [i for i in range(1, n + 1) if freq[i] == 1]
    
    adj = {}
    for i, (a, b, c) in enumerate(triples):
        arr = [a, b, c]
        for x in arr:
            for y in arr:
                if x != y:
                    adj.setdefault(x, []).append(y)
    
    # pick first endpoint
    start = ends[0]
    
    used = [False] * (n - 2)
    used_v = [False] * (n + 1)
    
    res = [start]
    used_v[start] = True
    
    if n == 1:
        print(start)
        return
    
    # choose second element
    nxt = None
    for v in adj.get(start, []):
        nxt = v
        break
    
    res.append(nxt)
    used_v[nxt] = True
    
    for _ in range(n - 2):
        a, b = res[-2], res[-1]
        candidates = set()
        for ti in where[a]:
            if used[ti]:
                continue
            x, y, z = triples[ti]
            if b in (x, y, z):
                candidates.update([x, y, z])
                break
        for v in candidates:
            if not used_v[v]:
                res.append(v)
                used_v[v] = True
                break
    
    print(*res)

if __name__ == "__main__":
    solve()
```该代码首先对出现次数进行计数以检测端点。 然后，它从三元组构建一个辅助邻接结构，这有助于从一个端点选择初始方向。 

重建阶段维护一个用于三元组的已用数组和一个用于值的已用数组。 在每一步中，它都会搜索包含最后两个选定元素的三元组，并提取第三个未使用的值。 由于保证了结构的一致性，因此该搜索总是成功而不会产生歧义。 

一个微妙的实现细节是确保我们永远不会重复使用已经放置在排列中的数字。 另一个是我们只需要包含当前对的三元组的局部一致性，而不是全局搜索。

 ## 边缘情况

 一个关键的边缘情况是多个三元组在重建早期包含重叠对。 在这种情况下，如果不强制执行“未使用的元素”约束，天真的贪婪选择可能会选择错误的扩展。 该算法通过标记已使用的值并将候选值限制为仅未使用的元素来避免这种情况。 

另一个边缘情况是当端点出现在也包含高频内部节点的三元组中时。 如果没有频率分析，人们可能会错误地选择中间元素作为起点，从而导致不明确的分支。 频率 1 规则可靠地隔离真实端点。 

最后，如果以任意顺序处理三元组，则朴素邻接图可能会建议多个下一个候选者。 滑动窗口结构保证每一步仅一个有效的未使用扩展，这即使在输入三元组严重加扰的情况下也可以防止不一致。
