 ## 解决方案
 ## 问题理解

 我们得到了一些相同的火柴棒，我们想将它们组合成一个十进制数。 根据标准七段显示配置，每个数字消耗固定数量的火柴棒。 只要我们有足够的火柴棒，我们就可以选择任何数字，而且我们不必使用所有的火柴棒。 结果数字最多只能使用给定的数字上限，这意味着答案中的每个数字不得大于`k`，并且数字本身不能以零开头。 

对于每个测试用例，我们必须在这些约束下构建数值上最大的可能值。 

关键的困难在于，问题不是任意求和或划分火柴棍，而是选择成本不同的数字。 这会产生组合优化问题，其中数字的值与消耗的资源不是线性的。 

约束允许最多 1000 个测试用例和值`n`最多 1000。任何尝试枚举所有数字组合或每个测试用例运行背包式 DP 的解决方案如果天真地实现，都有可能太慢，因为简单的 DP 大约是`O(nk)`每个测试用例或更糟。 

一个微妙的边缘情况是火柴棍在约束下无法形成任何有效数字`digit ≤ k`。 在这种情况下，答案应该是空的或实际上不可能，但典型的竞赛公式假设在给定允许的范围内至少有一位数字始终是可构造的。 另一个边缘情况是，贪婪策略提前选择了较小的数字，但稍后阻止形成更长的字典顺序更大的数字。 例如，选择消耗许多火柴棒的大数字可能会减少数字总数并导致总数减少。 

该问题还隐含着经典的“火柴棍数字”结构：数字 0-9 具有固定成本，按字典顺序最大化数字意味着首先最大化数字计数，然后最大化数字值。 

## 方法

 思考这个问题的一种强力方法是对火柴棒的数量和所使用的数字进行动态规划。 我们可以定义`dp[i]`作为我们可以使用精确形成的最佳数字`i`火柴棍，并通过尝试所有数字进行转换`0-k`。 每个转换都会比较按字典顺序构建的数字。 

这在原则上是正确的，因为每个有效数字都对应于一系列数字选择，并且 DP 探索所有这样的序列。 然而，每个状态都存储字符串，并且每次转换都需要比较或复制字符串，导致粗略地`O(n * k * length)`每个测试用例的操作。 和`n = 1000`和`t = 1000`，这已经远远超出了极限。 

问题的结构使得贪婪构造成为可能。 目标是字典序最大化，因此无论数字值如何，较长的数字总是比较短的数字更好。 这表明我们应该首先最大化我们可以形成的数字数量，然后最大化从左到右的每个数字。 

为了最大化数字数量，我们总是希望使用允许的数字中消耗最少火柴棒数量的数字`0..k`。 一旦长度固定，每个位置都可以用最大的数字贪婪地填充，同时仍然允许用最小成本的数字完成剩余的位置。 

这将问题从全局优化减少到基于剩余预算的局部可行性检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 字符串暴力破解 | O(n·k·n) | O(n·k·n) | O(n·k) | O(n·k) | 太慢了|
 | 贪心构造| O(n·k) 或 O(n) | O(n) | 已接受 |

 ## 算法演练

 我们假设标准数字来自七段显示器，这意味着每个数字都有固定的火柴棒要求。 

1. 计算每个数字的成本`0`到`k`。 我们只考虑以下数字`k`，因为禁止使用更大的数字。 如果超出火柴棒容量或无效，我们也会忽略无法表示的数字。 
2. 找出所有允许数字中的最小成本。 该数字是将火柴棍转换为数字计数的最有效方法，因此它决定了数字的最大可能长度。 
3. 计算最大位数`L`我们可以构建为`L = n // min_cost`。 
4.如果`L = 0`，不输出任何内容或处理不可能的情况。 这相当于火柴棍太少，甚至无法组成一个数字。 
5. 从左到右构造答案。 在每个位置，尝试从`k`下降到`0`。 
6. 对于候选数字`d`，检查选择它是否仍然允许我们在剩余的位置上完成有效的数字。 这需要验证选择后剩余的火柴棒`d`足以填满`remaining_positions`使用最小成本数字。 
7. 找到有效数字后，将其附加到答案中，从剩余火柴棒中减去其成本，然后继续。 

### 为什么它有效

 正确性依赖于两个耦合的不变量。 首先，在构建的任何阶段，算法始终在给定火柴棒预算的情况下保持最大可能的剩余数字计数。 这是可以保证的，因为数字计数是使用最小成本数字预先固定的，因此任何前缀选择都不会减少最佳长度。 

其次，在每个位置，选择最大的可行数字保留了完成数字其余部分的可能性。 由于使用最小成本数字来检查可行性，因此任何被拒绝的数字都将违反完成全长解决方案的能力，这意味着它不能属于最佳词典答案。 

因此，该结构在长度和字典顺序上都是贪婪的，并且后面的决策无法弥补之前的次优数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# Standard 7-segment matchstick costs
cost = [6,2,5,5,4,5,6,3,7,6]

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())

        allowed = list(range(k + 1))

        min_cost = min(cost[d] for d in allowed)

        L = n // min_cost
        if L <= 0:
            print(0)
            continue

        res = []
        remaining = n

        for pos in range(L):
            for d in range(k, -1, -1):
                c = cost[d]
                if remaining >= c:
                    rem_after = remaining - c
                    # check feasibility for remaining positions
                    if rem_after >= (L - pos - 1) * min_cost:
                        res.append(str(d))
                        remaining -= c
                        break

        print("".join(res))

if __name__ == "__main__":
    solve()
```该代码首先对数字的固定火柴成本进行编码。 然后，它计算允许的数字中最有效的数字成本，这确定了可实现的最大长度。 贪心循环逐位构建数字，始终首先尝试最大的数字，同时确保完成剩余位置的可行性。 

可行性检查是关键部分：它可以防止选择较大的数字，从而导致火柴棒不足以完成所需的数字数量。

 ## 边缘情况

 第一个边缘情况是当`k`非常小，比如`k = 0`或者`k = 1`。 在这种情况下，解决方案退化为仅使用单个数字，并且算法必须正确避免在贪婪选择期间尝试更大的数字。 

第二个边缘情况是当`n`略低于除最便宜的数字之外的任何允许数字的成本。 例如，如果最便宜的数字需要 5 根火柴棍并且`n = 4`，正确的输出为空或零，并且算法不得尝试构造部分数字。 

第三种边缘情况是，字符串早期的贪婪数字选择似乎有益，但后来却阻碍了可行性。 可行性检查通过强制每个前缀必须仍然允许以最小成本数字完成来防止这种情况，确保不会做出不可逆转的选择。
