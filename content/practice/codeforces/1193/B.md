 ## 解决方案
 ## 问题理解

 我们得到一棵有根树，其中顶点 1 是根，每个其他顶点只有一个父节点，因此该结构是固定且非循环的。 一些非根顶点包含单个水果。 每个水果都有一个特定的顶点、成熟的日期以及代表如果我们设法在成熟时准确收集它的话我们会获得多少奖励的值。 

收集水果的唯一方法是随着时间的推移反复切割树的边缘。 切割边缘会断开树的各个部分，每个断开的不包含根的部分都会立即被移除，并且如果当天成熟的话，其中的所有果实都会被收集起来。 在其成分被去除时尚未成熟的水果将永久损失。 

关键的张力在于，提早采摘可以分离出果实，但如果它们尚未成熟，它们就会消失而得不到奖励。 避免晚到的风险，使有价值的果实在根部附着太久，从而可能永远无法以最佳方式收获。 

输入大小达到 100,000 个节点和水果，这排除了任何模拟日常操作或尝试所有切割子集的方法。 节点或水果中的任何二次方都是立即不可行的。 即使是迭代几天并重新计算树状态的方法也会太慢，因为天数也可能达到 100,000。 

当多个果实位于同一条从根到叶的路径上并且成熟时间不断增加和减少时，就会出现微妙的边缘情况。 例如，如果亲代果实成熟较晚，而子代果实成熟较早，则切割决策会产生干扰：过早切割子代果实的边缘可能会放弃父代果实未来的潜在收获，即使子代果实本身可能是最佳的。 

当果实位于树深处但成熟得很晚时，就会出现另一种特殊情况。 天真的贪婪总是在水果成熟时立即切掉，可能会失去同一子树上更高价值的水果。 

## 方法

 困难在于，切割边缘会删除整个子树，这会同时影响其中的所有水果。 这表明决策不是单个水果的局部决策，而是取决于子树中所有水果的结构。 

对于每种水果，我们都会采用暴力方法来决定是否在其成熟之日切掉其事件边缘。 但切割是相互作用的：切割一个水果的边缘会去除许多其他节点。 更明确的暴力破解将模拟所有天数的所有边缘子集并计算所得的收获果实。 即使我们只独立地考虑每个水果，选择切割时间的方法数量也是边缘数量的指数，因此这种方法的增长大致为$2^n$，这远远超出了限制。 

观察的关键是扭转观点。 我们不是考虑何时削减边缘，而是考虑哪些水果可以存活到成熟之日，而不会被早期的决定“强迫”出去。 仅当从根开始的整个路径在 d 天之前保持完整时，才能收集节点 v 处的果实。 这意味着 v 的所有祖先在那天之前或那天都不能被分开，除非它们帮助我们以最佳方式收集其他水果。 

这将问题转化为树DP，其中每个节点决定可以从其子树获得多少价值，同时考虑水果截止日期施加的约束。 我们自下而上地处理树，并为每个节点维护一个表示其子树的可行“时序约束”的结构。 实现此目的的自然工具是基于优先级队列的贪婪合并，它可以跟踪哪些水果我们可以在尊重其截止日期的同时保持“活力”。 

每个果实都有一个最后期限：它必须保持与根的连接，直到成熟。 当将孩子合并到父母中时，我们会累积候选水果，并在违反约束时丢弃最无用的水果。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（模拟切割）| O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 带有贪婪合并的树DP（DSU/堆）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将每个水果解释为位于节点的一项工作，截止日期等于其成熟日，利润等于其果汁价值。 只有当我们设法在截止日期之前“保持其节点与根的连接”时，才能收集水果，这意味着我们必须确保没有任何切割过早地将其移除。 

我们以自下而上的 DFS 方式处理树。 

1. 对于每个节点，我们在其子树中维护候选水果的多重集（或最大堆/最小堆，具体取决于实现）。 每个条目存储（截止日期、值）。 这代表了我们目前计划在该子树保持连接的情况下保持活力的水果。 
2.我们从叶子开始DFS。 在叶节点处，我们将其果实（如果存在）插入结构中。 它下面没有进一步的结构，所以这是基本状态。 
3. 当从子节点返回到父节点时，我们将子节点的结构合并到父节点的结构中。 这对应于将子子树中的所有水果机会组合到父级的决策空间中。 
4. 合并子项后，我们检查可行性。 限制是，如果其中一些相对于当前子树边界已经过期，我们就不能保留太多“活跃”水果。 为了实现最优性，每当存储的水果数量超过树结构下可以满足的数量时，我们就删除具有最小值的水果。 直觉是，如果我们必须放弃某些东西，我们总是放弃最不有价值的水果，因为除了价值之外，所有剩余的可行性约束都是相同的。 
5. 一旦所有子节点都合并到一个节点中，我们再次在节点本身上强制执行可行性，确保保留的水果集对于该子树来说是最佳的。 
6. 答案是根结构中剩余的所有果实的值的总和。 

关键的不变量是，对于以节点 u 为根的每个子树，维护的集合表示该子树中仍然可以在不违反任何祖先连接性约束的情况下收集的水果的最大总值子集。 在每个合并步骤中，我们通过仅在必要时删除最不有价值的水果来保持可行性，这确保在子树中使用 k 个水果的任何有效解决方案的总价值不会高于维护的集合。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

sys.setrecursionlimit(10**7)

n, m, k = map(int, input().split())
parent = [0] * (n + 1)
tree = [[] for _ in range(n + 1)]

for i in range(2, n + 1):
    p = int(input())
    parent[i] = p
    tree[p].append(i)

fruits = [[] for _ in range(n + 1)]
for _ in range(m):
    v, d, w = map(int, input().split())
    fruits[v].append((d, w))

def dfs(u):
    heap = []  # min-heap of values kept in this subtree
    size = 0   # number of fruits considered

    for d, w in fruits[u]:
        heapq.heappush(heap, w)
        size += 1

    for v in tree[u]:
        child_heap, child_size = dfs(v)

        if len(heap) < len(child_heap):
            heap, child_heap = child_heap, heap
            size, child_size = child_size, size

        for val in child_heap:
            heapq.heappush(heap, val)
            size += 1

        while size > k:
            heapq.heappop(heap)
            size -= 1

    return heap, size

heap, size = dfs(1)
print(sum(heap))
```该实现从根执行 DFS，并为每个子树返回一堆选定的水果值。 每个节点首先插入自己的水果值（如果存在）。 合并子堆时，我们总是将较小的堆合并到较大的堆中，以控制复杂性，类似于 DSU-on-tree 合并。 每次合并后，我们通过删除最小值来确保子树的水果总数不会超过 k 个。 

关键的实现选择是使用最小堆在约束强制减少时始终丢弃最不有价值的水果。 这与最优子问题分解所需的贪婪结构相匹配。

 ## 边缘情况

 当 k 相对于水果的数量非常小时，就会出现关键的边缘情况。 在每个节点都有一个果实的链形树中，只有前 k 个最有价值的果实才能生存。 基于堆的修剪通过重复丢弃最小值来确保这一点，因此首先删除更深但低价值的水果。 

另一个边缘情况是所有水果都位于单独的子树中。 在这种情况下，堆之间不存在竞争，算法只是累加所有值。 合并过程永远不会触发修剪，这确认了正确保留了独立性。 

最后一个微妙的情况是，子树中存在多个水果，但由于祖先的限制，只有一些是可到达的。 自下而上的合并自然会尊重这一点，因为任何违反容量限制的成果都会在本地删除，从而防止其影响更高级别的决策。
