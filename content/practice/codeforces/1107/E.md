 ## 解决方案
 ## 问题理解

 我们得到一个二进制字符串，我们可以重复压缩它，直到没有任何内容为止。 一次移动包括选择一个连续的相同字符块，或者全部`0`或全部`1`s，从字符串中删除该块，然后连接其余部分。 每次我们删除一个长度的块`x`，我们赚`a[x]`点，其中奖励仅取决于删除的段的大小。 

目标是选择删除的顺序和分组，以便最终删除每个角色并使总分最大化。 

重要的结构特性是删除会重塑字符串。 删除块后，先前分离的段变得相邻，这可能会改变未来的合并机会。 这使得该过程成为非本地的：删除段的价值取决于它与双方的交互方式。 

约束很小，有`n ≤ 100`，这立即表明任何三次甚至四次动态规划解决方案都是可以接受的。 这是一个强烈的暗示，即状态必须描述字符串的间隔，因为只有大约`n^2`子串。 

天真的贪婪方法很快就会失败，因为局部最优删除可能会阻止以后更好的合并。 例如，提前删除一个小块可能会分割一个区域，否则该区域可能会合并成一个大的高价值块。 

典型的故障场景看起来像一个字符串`110011`。 如果我们贪婪地移除`00`首先，因为它目前可以作为中间块移除，我们可能会破坏形成更长的可能性`11...11`稍后细分，失去更大的奖励`a[x]`。 

另一个微妙的边缘情况是只有在多次删除后才能进行合并。 仅考虑原始字符串中连续段的解决方案将完全错过这些未来的合并。 

## 方法

 暴力策略将尝试所有可能的删除序列。 在任何步骤中，我们都会选择一个有效的段，将其删除，然后对结果字符串进行递归。 然而，每次移除都会改变邻接关系，并且最多可以有`O(n)`每一步的选择，有深度`O(n)`，产生一个指数搜索空间，大约为`O(n!)`或者更糟，取决于分支行为。 即使对于`n = 20`。 

关键的观察结果是，删除的顺序仅通过它如何允许段合并而起作用。 我们可以根据间隔以及是否允许端点通过中间删除进行合并来描述问题，而不是跟踪整个演变的字符串。 

这是一个经典的区间动态规划问题，我们计算删除子串的最佳方法`s[l..r]`假设如果我们正确对齐匹配的字符，它最终可能会崩溃为单个合并块。 

中心思想是定义一个DP状态，捕获删除一个区间的最佳分数，然后仔细处理端点匹配并且清除中间后可以合并的情况。 

我们要么单独删除左端点，要么在清除它们之间的子字符串后尝试将其与区间内的匹配字符配对。 这将问题转化为分区间隔和可选地合并匹配端点。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |
 | 间隔 DP | O(n^3) | O(n^3) | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 我们定义`dp[l][r]`作为完全删除子串可获得的最大分数`s[l..r]`。 

我们还依赖于隐式转换内部段合并的前缀处理。 

### 步骤

 1. 初始化`dp[l][l] = a[1]`对于所有单个字符，因为单个字符是大小为 1 的可移动块。 
2. 考虑从 2 到 2 的所有子串长度`n`。 对于每个间隔`[l, r]`，我们尝试计算`dp[l][r]`。 
3. 首先，考虑将区间分成两个独立的部分。 对于每一个`k`在`[l, r-1]`， 更新`dp[l][r] = max(dp[l][r], dp[l][k] + dp[k+1][r])`。 

这相当于分别删除左右部分，没有任何交互。 
4. 接下来，尝试利用端点合并。 对于每一个`k`这样`s[k] == s[l]`，我们考虑使`s[l]`和`s[k]`属于同一个最终移除组。 为此，我们必须完全删除中间段`[l+1, k-1]`首先，这样`l`和`k`变得相邻。 

清除中间后，我们有效地将端点合并成单个块，其大小是匹配结构的组合贡献。 我们更新：`dp[l][k] = max(dp[l][k], dp[l+1][k-1] + a[2])`在最简单的合并解释中，但总的来说，我们通过确保在清除中间时可以将端点视为已连接，将其合并到分区中。 
5.最终答案是`dp[1][n]`。 

### 为什么它有效

 DP 保持不变式`dp[l][r]`始终代表完全删除独立子串的最佳可实现分数`[l, r]`，假设与外部字符的所有交互都是无关的，因为该间隔最终被删除所隔离。 

每个有效的删除序列都有一个删除某些连续块的最后一个操作。 该块要么对应于间隔的分区，要么对应于内部区域已被预先完全清除的合并结构。 转换准确地枚举了这些可能性，确保在不首先清除介入字符的情况下不会错过任何有效的最终移动，并且不会对无效合并进行计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input().strip())
s = input().strip()
a = [0] + list(map(int, input().split()))

dp = [[0] * n for _ in range(n)]

for i in range(n):
    dp[i][i] = a[1]

for length in range(2, n + 1):
    for l in range(n - length + 1):
        r = l + length - 1

        dp[l][r] = 0

        for k in range(l, r):
            dp[l][r] = max(dp[l][r], dp[l][k] + dp[k + 1][r])

        if s[l] == s[r]:
            best_mid = 0
            if l + 1 <= r - 1:
                best_mid = dp[l + 1][r - 1]
            dp[l][r] = max(dp[l][r], best_mid + a[length])

print(dp[0][n - 1])
```DP 表是通过增加间隔长度自下而上构建的，确保所有较小的子问题在需要之前得到解决。 分割过渡是标准间隔划分步骤，而合并过渡仅在端点匹配时激活，从而允许在清除内部后将整个间隔视为一个可移动块。 

一个微妙的实现细节是在以下情况下处理空的内部情况：`l+1 > r-1`。 在这种情况下，合并的贡献减少为直接的单个块删除，因为子串在端点处已经是统一的。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input().strip())
    s = input().strip()
    a = [0] + list(map(int, input().split()))

    dp = [[0] * n for _ in range(n)]
    for i in range(n):
        dp[i][i] = a[1]

    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1
            best = 0

            for k in range(l, r):
                best = max(best, dp[l][k] + dp[k+1][r])

            if s[l] == s[r]:
                mid = dp[l+1][r-1] if l+1 <= r-1 else 0
                best = max(best, mid + a[length])

            dp[l][r] = best

    return str(dp[0][n-1])

 ## 边缘情况

 关键的边缘情况是当子串具有匹配的端点但有一个重要的中间部分时，必须在合并之前完全擦除该中间部分。 例如，`s = "10001"`。 

为了`[0,4]`，该算法考虑`s[0] == s[4]`，因此它尝试合并。 它计算`dp[1][3]`，表示完全删除内部`"000"`。 一旦删除，端点就会变得相邻并且可以被视为单个块。 最终值变为`a[5]`，它正确地捕捉到了合并整个区间的好处。 

仅检查原始字符串中连续相同运行的天真的解决方案在这里会失败，因为它永远不会考虑两个外部`1`删除中间段后可以合并s。
