 ## 解决方案
 ## 问题理解

 我们给定一个大小为的方阵$n \times n$，但不是显式地写为位，而是将每一行打包为十六进制字符。 每个十六进制数字代表四个二进制单元，因此输入只是二进制矩阵的紧凑编码。 

任务是找到最大的块大小$x$这样矩阵就可以被“压缩”成更小的网格$\frac{n}{x} \times \frac{n}{x}$。 压缩意味着如果我们将矩阵分割成不重叠的$x \times x$块，那么单个块内的每个单元格必须具有完全相同的值。 不同的块允许有差异，但在一个块内没有变化。 

因此，条件不是关于全局重复，而是关于网格固定分区内的局部均匀性。 

这些限制迫使我们走向$O(n^2)$或附近$O(n^2 \log n)$解决方案。 自从$n \le 5200$， 一个$O(n^2)$通行证已经在附近$2.7 \times 10^7$细胞，这很好。 不可接受的是对许多候选值重复进行全矩阵扫描$x$，因为除数的数量仍然足够大，足以推动我们进行数十亿次运算。 

一个天真的方法会尝试每个除数$x$的$n$并通过扫描所有块来验证每个块$x^2$细胞。 这会变得很慢，因为每次检查都会花费$O(n^2)$，并且多次执行会使成本成倍增加。 

当人们假设周期性重复而不是块独立时，就会出现一种微妙的失败情况。 例如，在一个矩阵中，其中每个$4 \times 4$块是恒定的，但不同的块会有所不同，将其视为完全周期性的网格会错误地拒绝有效的压缩。 

另一个失败案例来自于没有仔细处理十六进制解码。 每个字符扩展为四位，并且将位映射到单元中的任何差一都会改变结构并破坏块对齐检查。 

## 方法

 蛮力策略从定义开始。 对于每位候选人$x$，我们将矩阵划分为$x \times x$块并验证每个块仅包含一个不同的值。 对于每个块，我们扫描其所有单元格。 这是正确的，因为它直接强制执行压缩条件。 

问题是重复。 每一项检查都已经涉及到所有$n^2$单元格，并且对许多除数执行此操作会使总工作量太大。 

关键的观察是我们不需要重复地重新扫描每个块内的每个单元。 如果一个块的所有值都相同，则该块是有效的，这对于二进制矩阵来说相当于说该块中的值的总和是$0$或者$x^2$。 如果我们维护 2D 前缀和，这会将每个块检查转换为恒定时间查询。 

一旦前缀和可用，每个候选者$x$可以通过迭代其来验证$\left(\frac{n}{x}\right)^2$块并检查每个块的总和$O(1)$。 这减少了每个候选检查与块的数量而不是单元的数量成比例。 

因为我们只测试除数$n$，并且所有除数的总工作形成块计数上的类似谐波的总和，总复杂度保持接近$O(n^2)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2 \cdot d(n))$|$O(1)$| 太慢了 |
 | 每个除数的前缀和 |$O(n^2)$|$O(n^2)$| 已接受 |

 ## 算法演练

 ### 步骤 1：将输入解码为二进制矩阵

 每个十六进制字符都扩展为四位。 我们构建了一个完整的$n \times n$矩阵$A$仅包含 0 和 1。此步骤是必要的，因为所有后续推理都依赖于直接单元格访问。 

### 步骤 2：构建 2D 前缀和数组

 我们构造一个前缀和表，其中每个条目存储矩形中从左上角到该位置的个数。 这允许我们在常数时间内查询任何子矩阵的总和。 这是替代重复扫描的机制。 

### 步骤 3：枚举所有因数$n$我们生成所有有效的块大小$x$这样$n \bmod x = 0$。 只有这些值才有意义，因为网格必须可划分为相等的块。 

### 第 4 步：对于每个候选人$x$, 验证所有块

 我们将矩阵划分为$x \times x$块。 对于每个块，我们使用前缀和来计算 1 的数量。 如果总和既不是$0$也不$x^2$，则该块包含混合值和候选值$x$无效。 

### 第 5 步：跟踪最大有效值$x$我们迭代所有候选者并存储通过验证的最大候选者。 这就是最终的答案。 

### 为什么它有效

 每个块必须对应于压缩矩阵中的单个值。 对于二元矩阵来说，一个块有效就相当于是常数，相当于sum为0或者满。 前缀和保证我们只检查每个块一次而不会产生歧义。 由于每个单元都属于固定的一个块$x$，验证充分表征了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_matrix(n):
    A = [[0] * n for _ in range(n)]
    for i in range(n):
        row = input().strip()
        col = 0
        for ch in row:
            v = int(ch, 16)
            for k in range(3, -1, -1):
                if col < n:
                    A[i][col] = (v >> k) & 1
                    col += 1
    return A

def build_prefix(A, n):
    ps = [[0] * (n + 1) for _ in range(n + 1)]
    for i in range(n):
        row_sum = 0
        for j in range(n):
            row_sum += A[i][j]
            ps[i + 1][j + 1] = ps[i][j + 1] + row_sum
    return ps

def rect_sum(ps, x1, y1, x2, y2):
    return ps[x2][y2] - ps[x1][y2] - ps[x2][y1] + ps[x1][y1]

def solve():
    n = int(input())
    A = build_matrix(n)
    ps = build_prefix(A, n)

    def ok(x):
        for i in range(0, n, x):
            for j in range(0, n, x):
                total = rect_sum(ps, i, j, i + x, j + x)
                if total != 0 and total != x * x:
                    return False
        return True

    best = 1
    for x in range(1, n + 1):
        if n % x == 0 and ok(x):
            best = x

    print(best)

if __name__ == "__main__":
    solve()
```解码步骤仔细地将每个十六进制数字按正确的顺序处理成四位，确保位对齐与原始矩阵布局匹配。 前缀和是使用基于 1 的索引构建的，因此子矩阵查询不需要边界检查。 

验证功能通过仅扫描块原点而不是单个单元来检查每个候选块大小。 矩形和查询隔离每个$x \times x$恒定时间内的区域，这是核心优化。 

整个循环$x$是安全的，因为除数的数量是有限的，并且由于前缀和，每次检查都是有效的。

 ## 边缘情况

 完全均匀的矩阵是最简单的情况。 每一位候选人$x$通过，因为每个块总和总是$x^2$。 该算法自然地处理这个问题，因为前缀和总是返回每个块的完全覆盖。 

棋盘图案对于每一个都失败$x > 1$。 在这种情况下，块和总是混合的，并且第一个失败的检查立即发生在第一个无效块内，确保尽早拒绝而不扫描不必要的区域。 

仅在大的连续区域中均匀但与块边界不对齐的矩阵说明了对齐的重要性。 即使大区域共享值，如果它们错误地跨越块边界，总和条件也会精确检测边界块处的不一致。
