 ## 解决方案
 ## 问题理解

 给定一棵最多有 100,000 个节点的树，我们必须为每个节点分配一个从“A”到“Z”的字母。 这些字母代表等级，其中“A”是最强的，“Z”是最弱的。 

该约束是全局且成对的：如果两个不同的节点获得相同的排名，则它们之间的每条简单路径必须包含至少一个具有严格更好排名的节点。 换句话说，相同的等级不允许仅通过相等或更差的等级形成“不受保护”的连接。 每对相等的字母必须由其连接路径上某处的严格更高级别的节点分隔开。 

输出是对节点的字母的任何有效分配，或者是不存在此类分配的声明。 

树的大小达到 100,000 个节点，因此任何解决方案都必须接近线性或对数线性。 路径上的任何二次甚至边界二次都立即不可能，因为节点对的数量巨大，甚至重复遍历路径也会超出时间限制。 

当树结构“过于线性”时，就会出现微妙的边缘情况。 例如，长度大于 26 的链不能通过简单的贪婪重用字母来安全地分配，因为我们仅限于 26 个等级，并且重复的等级必须始终由严格更高的等级分隔。 另一个棘手的情况是，当高度节点强制在不同分支中重复重用等级时，如果我们不仔细控制重用，这可能会默默地违反路径条件。 

## 方法

 一个蛮力的想法是尝试增量分配字母，同时在每次分配后检查有效性。 在节点上放置一个字母后，我们将验证对于每个先前分配的具有相同字母的节点，路径条件是否成立。 这需要检查树中的路径，并且每次检查可能需要 O(n) 时间。 由于我们可能执行 O(n) 分配并可能与许多先前的节点进行比较，因此最坏情况的复杂度变为 O(n^2) 或更糟，这对于 100,000 个节点来说是不可用的。 

关键的见解是将约束转化为树上的结构分解问题。 该条件与递归分离规则非常相似：如果我们为节点分配尽可能小的标签（“A”），那么一旦删除该节点，具有相同标签的所有节点都必须位于不同的连接组件中。 这是因为具有相同标签的两个节点之间的任何路径都会经过该所选节点，该节点严格来说更好，因此满足规则。 

这自然意味着树上的分而治之。 我们反复选择一个“类质心”节点作为下一个最高优先级标签，将其删除，然后递归地求解子树。 然而，与经典的质心分解不同，我们并没有最小化子树大小，而是贪婪地构建移除层，同时确保剩余结构仍然有足够的“排名预算”。 

在每一步中，我们选择一个节点，以保证在删除后，仍然可以使用最多剩余的 25 个等级来标记所有生成的组件。 这导致了质心分解策略，其中分解树的深度成为指定的字母。 

分解树的高度最多为 26，因为我们只有 26 个标签。 如果在任何时候我们需要比 26 层更深的递归，答案是不可能的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 质心分解| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们构建树的质心分解并根据分解深度分配字母。

1. 将整棵树视为一个活动组件。 我们为当前递归级别中仍然“活动”的节点维护一个标记。 每一步的目标是选择一个节点，通过删除该节点将组件分割成平衡的部分。 
2. 使用 DFS 计算仅限于活动节点的子树大小。 这使我们能够评估哪个节点可以作为质心。 我们需要子树大小的原因是为了确保结果组件不会变得太大，否则会迫使递归比允许的更深。 
3. 找到当前组件的质心节点。 质心被定义为一个节点，删除它后不会留下大于当前组件大小一半的连接组件。 此属性可确保递归深度保持受控。 
4. 为当前质心分配一个与当前递归深度相对应的字母，从“A”开始。 直觉是，较高优先级的字母对应于较早的、全局分离的节点。 
5. 将质心标记为已移除，并递归地将相同的过程应用于移除后形成的每个连接组件。 
6. 如果递归深度在任何一点超过 26，则停止并返回“不可能！”，因为我们已经用尽了所有可用的等级。 

### 为什么它有效

 质心属性保证每个递归调用沿每个递归路径将组件大小至少减少一半。 这将递归深度限制为 O(log n)。 由于我们最多只需要 26 个不同的标签，因此任何强制深度大于 26 的树都无法进行有效着色。 

更重要的是，仅在一个递归级别内分配相同的字母可确保具有相同标签的任何两个节点位于由更高级别的质心分隔的不同分支中。 该质心节点具有严格更好的等级，满足任何相同等级对在其路径上被严格更高等级的节点分隔的要求。 

因此，分解直接编码所需的优势条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n)]
for _ in range(n - 1):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    g[a].append(b)
    g[b].append(a)

parent = [-1] * n
sub = [0] * n
used = [False] * n
ans = [''] * n

def dfs_size(u, p):
    sub[u] = 1
    for v in g[u]:
        if v != p and not used[v]:
            dfs_size(v, u)
            sub[u] += sub[v]

def dfs_centroid(u, p, total):
    for v in g[u]:
        if v != p and not used[v]:
            if sub[v] > total // 2:
                return dfs_centroid(v, u, total)
    return u

def collect(u, p, comp):
    comp.append(u)
    for v in g[u]:
        if v != p and not used[v]:
            collect(v, u, comp)

def decompose(u, depth):
    dfs_size(u, -1)
    c = dfs_centroid(u, -1, sub[u])

    if depth >= 26:
        print("Impossible!")
        sys.exit(0)

    ans[c] = chr(ord('A') + depth)
    used[c] = True

    for v in g[c]:
        if not used[v]:
            comp = []
            collect(v, c, comp)
            decompose(v, depth + 1)

decompose(0, 0)
print(" ".join(ans))
```该实现为树构建邻接列表并维护标记已删除节点的全局数组。 质心搜索使用仅限于活动节点的子树大小。 选择质心后，它会分配适当的字符并将其从进一步的递归中删除。 

一个微妙的细节是计算子树大小和收集组件之间的分离。 首先计算子树大小以正确定位质心，然后探索邻居以将图拆分为独立的递归调用。 这可以防止将已删除的节点混合到大小计算中。 

递归深度检查直接强制执行 26 个字母的约束。

 ## 边缘情况

 单个长链暴露了最深的递归要求。 当树是路径时，质心分解仍然通过重复选取中间节点来进行。 每个选定的质心将链分成两个较小的链，这确保相同的字母仅出现在由更高等级的质心分隔的不相交的段中。 

高度明星是另一个关键案例。 必须始终选择中心作为第一个质心，因为否则分配给不同叶子的相同标签将违反其路径经过更高等级节点的要求。 质心策略会自动处理这个问题，因为中心始终是组件的平衡点。
