 ## 解决方案
 ## 问题理解

 我们有两个循环的字符串列表。 第一个列表有大小$n$，第二个有大小$m$。 每年$y$通过采取产生一个名称$y$第一个列表中的第一个字符串和$y$- 第二个列表中的第一个字符串，两者都循环索引，并将它们连接起来。 

具体来说，第一年使用$s_1$和$t_1$, 第 2 年使用$s_2$和$t_2$， 等等。 一旦我们通过了任一列表的末尾，我们就会再次回到开头。 年份的名称只是所选对的串联。 

每个查询给出一个年份数$y$，可能非常大，我们必须输出结果的串联名称。 

主要的结构细节是两个序列都是周期性的。 第一个重复每个$n$年，第二次$m$年，因此组合模式每隔一年就会重复一次$\mathrm{lcm}(n, m)$年。 这种周期性使得大型查询变得易于管理。 

对于数组来说约束很小，$n, m \le 20$，所以预计算很简单。 查询次数也很少，但是年份索引可以上到$10^9$，这立即排除了逐年模拟的可能性。 任何迭代到的解决方案$y$在最坏的情况下，每个查询都会严重超时。 

天真的想法的一个微妙的失败案例是忘记循环索引。 例如，如果$n = 3$，访问$s_{y}$直接会出界$y > 3$。 另一个常见错误是使用基于 0 的索引错误地计算模，尤其是在将年份 1 映射到索引 0 时。 

## 方法

 暴力破解的想法是模拟每个查询的过程。 对于给定年份$y$，我们重复计算两个数组中的索引：$(y-1) \bmod n$和$(y-1) \bmod m$，然后连接相应的字符串。 这是正确的，而且非常直接。 

然而，如果通过从第一年迭代到$y$对于每个查询，成本变为$O(q \cdot y)$，这是不可能的，当$y$可以达到$10^9$。 即使与$q \approx 2000$，这会爆炸。 

关键的观察是，每年可以使用模算术在恒定时间内独立计算。 序列是周期性的，因此我们永远不需要模拟转换。 整个问题简化为索引两个循环数组并将结果连接起来。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟|$O(q \cdot y)$|$O(1)$| 太慢了|
 | 直接模块化索引|$O(q)$|$O(1)$| 已接受 |

 ## 算法演练

 1.读取两个数组$s$和$t$，并存储它们的长度$n$和$m$。 它们定义了两个独立的循环。 
2. 对于每个查询年份$y$，通过减去 1 将其转换为从零开始的索引。这会将年份 1 与索引 0 对齐，从而简化了模运算。 
3. 将第一个数组中的索引计算为$(y-1) \bmod n$。 这给出了正确的循环位置$s$。 
4. 将第二个数组中的索引计算为$(y-1) \bmod m$。 这给出了正确的循环位置$t$。 
5. 输出串联$s[i] + t[j]$。 

每个查询都是独立的，因此不需要存储中间结果或模拟进程。 

### 为什么它有效

 两个序列都以固定周期重复$n$和$m$。 这$y$重复循环中的第 - 个元素仅取决于其位置以循环长度为模。 由于输出只是两个独立周期的成对组合，因此整个系统也是周期性的，并且每个查询减少为两个模块化查找。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
s = input().split()
t = input().split()

q = int(input())

for _ in range(q):
    y = int(input())
    y -= 1
    print(s[y % n] + t[y % m])
```该解决方案直接应用模块化索引。 唯一重要的实现细节是在取模之前减去 1，确保年份 1 映射到索引 0。如果不进行此调整，年份边界将错误地移动。 

每个查询都是在恒定时间内独立处理的，因此不存在超出标准整数处理范围的状态累积或溢出风险。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(q)$| 每个查询执行恒定时间取模和串联 |
 | 空间|$O(n + m)$| 两个输入序列的存储 |

 这些约束允许最多 2000 个查询和非常小的数组，因此每个查询的恒定时间很容易足够快。 即使有 Python 开销，该解决方案也能轻松满足限制。 

## 测试用例```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    s = input().split()
    t = input().split()
    q = int(input())
    out = []
    for _ in range(q):
        y = int(input())
        y -= 1
        out.append(s[y % n] + t[y % m])
    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

 ## 边缘情况

 一个关键的边缘情况是$n = 1$或者$m = 1$。 在这种情况下，每年总是从该序列中选择相同的字符串。 模块化表达式仍然有效，因为任何数字模 1 都是 0，因此实现自然会正确崩溃，无需特殊处理。 

另一种情况是非常大的年份值接近$10^9$。 由于 Python 原生处理大整数，唯一的风险是忘记在求模之前减 1。 如果我们跳过这一点，第 1 年会错误地映射到索引 1 而不是 0，从而移动每个输出。 

最后一个微妙的情况是两个序列具有不同的长度并且不在小范围内周期性对齐。 即使如此，模块化方法仍然是正确的，因为每个序列独立循环，并且我们从不假设共享周期。
