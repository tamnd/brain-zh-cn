 ## 解决方案
 ## 问题理解

 我们需要所有长度排列中的帧段总数`n`。 

对于固定排列，一个段`[l, r]`当其中的值形成一组连续整数时，就会被框架化。 由于排列中的所有值都是不同的，因此条件$$\max - \min = r - l$$确切地说，该段包含其最小值和最大值之间的每个整数。 

排列的幸福度是它包含的框架片段的数量。 我们必须对所有排列进行求和，而不是计算一种排列的幸福感`n!`排列并输出对给定素数取模的结果`m`。 

约束条件`n ≤ 250000`彻底改变了问题的本质。 我们无法枚举排列，因为即使`20!`已经是巨大的了。 我们也无法负担任何检查单个排列的所有片段的算法。 该解决方案必须导出一个计数公式并在大致线性的时间内对其进行评估。 

一个微妙的点是我们同时对所有排列求和。 许多此类问题在颠倒计数顺序后变得容易处理：不是询问每个排列有多少个框架段，而是询问有多少个排列使特定段成为框架。 

另一个容易犯的错误是认为条件仅取决于位置。 例如，对于`n = 3`，长度段`2`仅当其两个值连续时才被成帧。 这对`(1,3)`不起作用，因为`3 - 1 = 2`而段长度减一等于`1`。 

为了`n = 1`，只有一种排列和一种线段。 答案是`1`。 任何公式都必须自然地产生这个值。 

## 方法

 让我们首先想象一下暴力解释。 

我们可以生成每个长度的排列`n`。 对于每个排列，我们可以检查每个段，计算其最小值和最大值，并检查它是否被框化。 即使对段查询进行了优化，也有`n!`排列，因此该方法几乎立即变得不可能。 为了`n = 10`, 已经有`3,628,800`排列。 

关键的观察结果是，框架段的定义仅取决于该段内的值集。 

考虑一段长度$$k = r-l+1.$$因为所有值都是不同的，所以条件$$\max - \min = k-1$$意味着该段恰好包含`k`连续的数字。 

假设这些连续的数字是$$x, x+1, \dots, x+k-1.$$这样的值集有多少种选择？ 起始值`x`可以选择在$$n-k+1$$方式。 

现在计算长度固定位置段的排列`k`正是包含那些`k`数字。 

这`k`所选值可以排列在段内`k!`方式。 

其余`n-k`值可以排列在段之外`(n-k)!`方式。 

因此，对于固定的段位置和固定的连续值块，有效排列的数量为$$k!(n-k)!.$$有`n-k+1`可能的连续值块以及`n-k+1`一段长度的可能位置`k`。 

因此所有长度的总贡献-`k`段是$$(n-k+1)^2 \cdot k! \cdot (n-k)!.$$对所有长度求和得出答案：$$\sum_{k=1}^{n} (n-k+1)^2 \cdot k! \cdot (n-k)!.$$剩下的任务是评估这个总和模`m`。 自从`n`取决于`250000`，我们可以预先计算阶乘模`m`在线性时间内计算总和，然后在另一个线性过程中评估总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!·n²) 或更糟 | O(n) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 阅读`n`和`m`。 
2. 预先计算阶乘模`m`。 

让`fact[i] = i! mod m`为所有人`0 ≤ i ≤ n`。 
3. 将答案初始化为零。 
4. 对于每个段长度`k`从`1`到`n`, 计算$$(n-k+1)^2 \cdot fact[k] \cdot fact[n-k] \pmod m.$$此数量计算所有对`(permutation, framed segment)`其段长度等于`k`。 
5. 将这个贡献添加到答案模数中`m`。 
6. 输出最终答案。 

步骤 4 起作用的原因是每个框架段恰好对应于一个连续值块，并且段位置、连续值块、段内排列和段外排列的每一个选择都会产生唯一的有效排列。 

### 为什么它有效

 固定长度`k`。 

一段长度`k`当且仅当其值恰好是某个集合时才被框定`k`连续整数。 有`n-k+1`这样的值集。 

在其中选择一个段位置`n-k+1`可能的职位。 一旦选择了连续的值集，`k`值可以在段内任意排序，从而有助于`k!`的可能性。 剩余的值可以在段外任意排序，从而有助于`(n-k)!`的可能性。 

包含该帧片段的每个排列都被精确计数一次，因为片段位置及其值集是唯一确定的。 

将所有片段长度上的这些计数相加，将每个排列中的每个框架片段恰好计数一次，这正是所需的总幸福感。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

fact = [1] * (n + 1)
for i in range(1, n + 1):
    fact[i] = fact[i - 1] * i % m

ans = 0

for k in range(1, n + 1):
    cnt = n - k + 1
    contrib = cnt * cnt
    contrib %= m
    contrib = contrib * fact[k] % m
    contrib = contrib * fact[n - k] % m
    ans = (ans + contrib) % m

print(ans)
```阶乘数组存储每个取模的值`m`。 由于所有后续计算也是以模为基础进行的`m`，不需要更大的值。 

循环结束`k`直接计算导出公式。 变量`cnt = n-k+1`出现两次是因为有两个独立的选择：段的位置和分配给它的连续值块。 

每次乘法后应用模可以防止中间数变得不必要的大。 Python 整数可以处理大值，但提前减少可以使实现更接近预期的模运算。 

索引特别容易出错。 贡献用途`fact[k]`和`fact[n-k]`， 不是`fact[k-1]`。 期限`n-k+1`来自对段位置和连续值块的计数。

# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % m

    ans = 0
    for k in range(1, n + 1):
        cnt = n - k + 1
        ans = (
            ans
            + cnt * cnt % m
            * fact[k] % m
            * fact[n - k]
        ) % m

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

 ## 边缘情况

 考虑最小的输入：```
1 993244853
```循环运行一次`k = 1`。$$(1)^2 \cdot 1! \cdot 0! = 1.$$算法输出`1`，匹配单个排列和单帧片段。 

考虑`n = 2`:```
2 1000000007
```贡献是$$2^2 \cdot 1! \cdot 1! = 4,$$和$$1^2 \cdot 2! \cdot 0! = 2.$$答案是`6`。 因为有两种排列，每种排列都有幸福`3`，总计为`6`。 这证实了计数正确地处理了占据整个数组的段。 

在计算连续值块时，会出现常见的差一风险。 为了`n = 3`和`k = 2`，正好有两个有效值块：$$\{1,2\}, \{2,3\}.$$该公式使用`n-k+1 = 2`。 使用`n-k`会错过一个区块并产生错误的总数。 该算法避免了这种情况，因为段位置和值块都使用相同的表达式进行计数`n-k+1`。 

另一个微妙的情况是`k = n`。 只有一个段位置，并且只有一个连续的值块，即来自`1`到`n`。 贡献变为$$1^2 \cdot n! \cdot 0! = n!,$$这正是整个数组段被框定的排列数。 由于整个数组的每个排列都满足此属性，因此计数是正确的。
