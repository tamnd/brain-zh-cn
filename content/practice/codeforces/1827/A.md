 ## 解决方案
 ## 问题理解

 我们有两个数组，`a`和`b`，每个长度`n`。 中的元素`a`都是不同的，同时`b`可能包含重复的数字。 任务是计算我们可以重新排序元素的方式数量`a`这样在重新排序后，对于每个索引`i`，条件`a[i] > b[i]`成立。 结果应以模数形式报告$10^9 + 7$。 

从概念上讲，认为`a`作为一组具有独特价值的卡片，`b`作为阈值。 我们需要为每张卡分配一个阈值，以便该卡严格超过阈值。 有效作业的数量就是最终答案。 

约束条件允许`n`一样大$2 \cdot 10^5$跨越所有测试用例，最多$10^4$测试用例。 这禁止任何显式尝试所有排列的解决方案，因为`n!`成长得太快，即使对于小`n`。 暴力阶乘方法是完全不可行的，因此我们需要一种利用排序和计数的方法。 

当所有元素都出现时，就会出现边缘情况`b`大于中的最大元素`a`。 例如，如果`a = [1, 2, 3]`和`b = [4, 5, 6]`，没有办法满足条件，所以输出必须是`0`。 当某些元素在`b`被重复。 如果`a`有足够大的元素但数量不够，天真的比较可能会错误地计算无效排列。 

## 方法

 简单的方法是生成所有排列`a`并检查每个排列是否满足`a[i] > b[i]`为所有人`i`。 这是正确的，但完全不切实际。 为了`n = 10`，这需要`10! = 3,628,800`每个测试用例的检查。 为了`n`如果是数百或数千，这将是一个天文数字。 

优化的关键见解是我们不需要直接考虑排列。 相反，我们可以对两者进行排序`a`和`b`并贪婪地分配元素。 如果`a`升序排列，我们可以尝试分配最大的`a`到最大的`b`它可以击败。 形式上，对于每个`b[i]`, 计算中有多少个元素`a`严格来说更大。 然后，对于每个位置，在考虑了先前使用的元素后，乘以可用的选择数量。 

这将问题简化为排序和线性计数。 对两个数组进行排序的成本`O(n log n)`，并迭代计算有效选择成本`O(n)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 排序+计数| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 对于每个测试用例，请阅读`n`和数组`a`和`b`。 
2. 数组排序`a`按升序排列。 排序确保我们可以轻松分配最小的`a`击败了`b`不跳过有效选项。 
3. 数组排序`b`按升序排列。 这使我们能够按照从最小到最大的顺序处理阈值。 分配最小的`b`首先最大化更大的选择`b`之后。 
4. 初始化变量`answer = 1`保存有效选择模的运行乘积$10^9 + 7$。 
5. 初始化索引`j = 0`跟踪当前候选人`a`。 迭代一遍`b`。 对于每个`b[i]`,数数有多少个`a[j]`满足`a[j] > b[i]`。 该职位的有效选择数为`count_available - i`在哪里`i`是的数量`b`已处理的值。 乘`answer`按此数模 (10^9 + 7`. If the count is zero or negative, immediately set `答案 = 0` 并中断。 
6.处理完所有元素后，打印`answer`。 

**为什么有效：** 排序`a`和`b`允许我们首先处理最小的阈值并分配最小的足够的卡。 不变量是对于每个`b[i]`，我们已经正确地计算了所有可用的`a[j]`尚未使用过的。 计数相乘反映了每个位置的独立选择的数量，保证了有效排列的正确总数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

def count_orders():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort()
        b.sort()
        
        answer = 1
        j = 0
        for i in range(n):
            while j < n and a[j] <= b[i]:
                j += 1
            choices = j - i
            if choices <= 0:
                answer = 0
                break
            answer = (answer * choices) % MOD
        print(answer)

count_orders()
```该解决方案首先要有效地读取输入。 排序`a`和`b`为贪婪分配做好准备。 这`while`循环确保我们跳过任何`a[j]`无法击败的`b[i]`。 计算`choices = j - i`占剩余数量`a`可以分配给当前的元素`b[i]`使用后`i`先前位置的元素。 乘法`answer`经过`choices`计算有效分配的总数模$10^9 + 7$。
