 ## 解决方案
 ## 问题理解

 我们给出了长度的排列$n$。 我们可以使用从位置开始的后缀$k+1$并自由地重新排列它，同时保留前缀$a_1 \ldots a_k$固定到位。 对于每个$k$，我们想知道在对后缀进行最佳排列后可以形成“完美间隔”的子数组的最佳数量。 

如果子数组的最大值减去最小值等于其长度减一，则该子数组是好的。 因为我们正在处理排列，所以这个条件相当于说子数组可以重新排列成连续的整数块，这意味着它恰好包含其最小值和最大值之间的所有整数，没有间隙或重复。 

所以任务不是检查固定间隔。 相反，我们选择如何重新排列后缀，以最大化最终数组中有多少个间隔表现得像“密集段”。 

关键的困难在于每次后缀重新排列都会同时更改许多子数组，并且我们必须评估每个前缀长度的最佳排列$k$，这实际上意味着考虑可以“塑造”尾部以最大化间隔密度的所有方式。 

约束很严格：总计$n$跨测试用例最多$2 \cdot 10^5$。 任何二次或偶数$O(n \sqrt{n})$每个测试用例太慢。 该结构表明每个元素必须以全球一致的方式在所有元素中做出贡献$k$，因此我们应该期望每个测试解决方案都是线性或接近线性的。 

一个天真的方法是，对于每个$k$，尝试后缀的所有排列，甚至尝试推理所有间隔分区。 甚至检查单个安排成本$O(n^2)$计算有效子数组的数量，并且后缀排列的数量呈指数级增长，因此这是不可能的。 

一个更微妙的陷阱是假设对后缀进行排序后，答案是固定的。 这是错误的，因为前缀与后缀相互作用：已经放置在前缀中的元素限制了可以跨边界形成的间隔数量。 

## 方法

 蛮力观点从修复开始$k$，然后尝试以各种可能的方式排列后缀并计算所有有效的子数组。 即使我们修复了一个排列，计算有效子数组也需要检查每一对$(l,r)$并验证最小值和最大值，即$O(n^2)$。 由于有$(n-k)!$后缀排列，这会立即爆炸。 即使我们将自己限制在单一的“合理”排序（例如排序），我们仍然无法有效地计算所有区间的最佳区间结构。$k$。 

关键的见解是停止考虑排列，而是考虑子数组如何成为有效间隔。 当子数组的值形成连续的整数段时，子数组才是有效的。 这个条件只取决于里面的元素是否能够无间隙地“堆积”起来。 

现在观察当我们自由决定后缀时会发生什么。 后缀是多个值的集合，我们可以按任意顺序放置它们。 前缀是固定的，就像部分构建的结构一样。 最好的策略始终是按照“有用”的递增顺序放置后缀元素，以形成新的连续片段。 这将问题简化为跟踪我们可以在相邻位置之间创建多少个“良好合并”。 

如果我们定义一个边界$i$和$i+1$，如果桥接边界所需的所有值都可以放置在后缀中或已经以兼容的方式存在于前缀中，则该边界变得“安全”。 每个这样的安全边界通过贡献额外的有效段来增加 copium 子阵列的数量。 

核心的减少是，我们不是直接推理子数组，而是跟踪可以消除多少个相邻间隙。 每个$k$对应于逐步将更多元素冻结到前缀中，这会降低灵活性。 答案变成了在删除最后一个灵活性后仍然可以满足多少邻接约束的累积计数。$n-k$元素。 

我们为每个位置预先计算它如何有助于形成或打破潜在的连续间隔，并维护有多少此类贡献保持活跃状态$k$增加。 这使我们能够使用贪婪扫描按其在区间形成中的作用排序的位置，在线性时间内维持答案。

 ## 算法演练

 1. 将每个值解释为从 1 到 的直线上的一个点$n$，并注意有效子数组对应于包含连续范围内的所有整数的区间。 这将任务重新定义为控制通过排列后缀元素可以形成多少个连续值范围。 
2. 预先计算排列中每个值的位置。 这让我们可以推断两个值何时可以通过重新排列后变得有效的子数组“连接”。 
3. 对于每对相邻的值$x$和$x+1$,确定最早的前缀长度$k$此后，不能再通过重新排列后缀将它们强制进入同一连续块。 此阈值捕获由于前缀约束而无法建立邻接的情况。 
4. 将每个这样的约束转换为一个事件$k$，一旦超过阈值，形成有效分段的能力就会降低。 这将问题转化为扫除$k$。 
5. 维护仍然可行的邻接连接数量的运行计数。 每个幸存的连接都会以可预测的加法方式增加 copium 子阵列的数量。 
6. 初始化答案$k=0$，其中完全的重新排列自由意味着可以最佳地实现每种可能的邻接结构。 
7. 扫一扫$k$从$0$到$n$，当超过其阈值时，将每个约束的贡献恰好减少一次。 将当前总数存储为该问题的答案$k$。 

### 为什么它有效

 正确性来自于以下事实：每个有效的 copium 子数组都对应于一组必须全部保持可满足的连续值约束。 每个约束仅取决于固定前缀后两个端点是否仍然可以放置在连续的区间内。 一旦前缀位置消除了灵活放置一个端点的能力，对于所有更大的端点来说，该约束将永久丢失$k$。 由于约束是独立且单调的$k$，一次扫描正确地计算出每个阶段仍可实现的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, v in enumerate(a):
            pos[v] = i

        # We track when each adjacency (x, x+1) becomes impossible
        events = [[] for _ in range(n + 2)]

        for x in range(1, n):
            l = min(pos[x], pos[x + 1])
            r = max(pos[x], pos[x + 1])
            # if prefix fixes anything inside (l, r), adjacency is restricted
            # threshold is r: once k > r, we lose flexibility
            events[r + 1].append(1)

        cur = 0
        ans = [0] * (n + 1)

        # initial value: all adjacencies potentially usable
        base = n * (n + 1) // 2

        for k in range(0, n + 1):
            if k > 0:
                for delta in events[k]:
                    cur += delta
            ans[k] = base - cur

        print(*ans)

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        pos = [0] * (n + 1)

        for i, v in enumerate(a):
            pos[v] = i

        # each adjacency contributes an interval until it becomes broken
        break_at = [0] * (n + 2)

        for x in range(1, n):
            l = min(pos[x], pos[x + 1])
            r = max(pos[x], pos[x + 1])
            break_at[r + 1] += 1

        cur = 0
        ans = [0] * (n + 1)

        base = n * (n + 1) // 2

        for k in range(n + 1):
            cur += break_at[k]
            ans[k] = base - cur

        print(*ans)

if __name__ == "__main__":
    main()
```该实现依赖于将问题简化为连续值之间的邻接约束。 位置数组允许恒定时间查找每个值在原始排列中的位置，这是必要的，因为只有相对顺序才关系到两个值是否可以分组为连续间隔。 

数组`break_at`存储当前缀大小超过某个阈值时准确丢失的邻接关系数量。 这避免了每个查询重新计算任何内容$k$。 最后的循环累积这些损失，并从固定基线中减去它们，该基线等于完全灵活的布置中潜在子阵列的总数。 

微妙的部分是，每个邻接都会对损失产生一次影响，我们必须确保只在正确的前缀边界处对其进行计数。 这就是为什么我们映射每一对$(x, x+1)$到$r+1$， 不是$r$。

 ## 边缘情况

 一个关键的边缘情况是排列已经排序。 在这种情况下，每个相邻对都完美对齐，并且从后缀中删除灵活性不会立即破坏许多邻接约束。 扫描正确地延迟了减少，产生逐渐减少而不是突然下降。 

另一个边缘情况是完全相反的排列。 这里每个邻接对都有很大的跨度，因此许多约束很早就变得活跃。 该算法处理这个问题是因为所有$r+1$事件在接近尾声时聚集，导致扫掠速度提前显着减少。 

最后，很小$n$案例如$n=1$或者$n=2$确认邻接构造中没有出现无效索引，因为循环结束了$x \in [1, n-1]$自然地变成空的或单步的，并且仍然产生正确的碱基计数。
