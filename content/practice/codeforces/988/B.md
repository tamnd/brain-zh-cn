 ## 解决方案
 ## 问题理解

 我们得到了一个字符串集合，并且可以以任何顺序重新排列它们。 重新排列后，我们需要一个非常具体的嵌套属性：每个字符串必须包含在其前面作为子字符串出现的所有字符串。 

换句话说，如果我们从头到尾排列字符串，那么每当我们在位置 i 处获取一个字符串时，位置 1 到 i − 1 中的每个字符串都必须作为连续的字符块出现在其中的某个位置。 

任务是判断这样的排序是否存在，如果存在，则输出一个有效的排序。 

约束很小：最多 100 个字符串，每个字符串的长度最多为 100。这立即告诉我们，即使检查所有对之间的子字符串关系也是可行的，在 O(n²·L) 时间内无需考虑优化问题。 我们所处的体制并不重视对数因素。 相反，排序逻辑的正确性才是核心难点。 

一些边缘情况比它们最初出现时更重要。 

其中一个问题是重复。 如果同一个字符串出现多次，则必须小心处理，因为字符串始终是其自身的子字符串，但对重复项进行排序并不会引入新信息。 

另一个微妙的情况是，在最终排序中稍后出现较短的字符串。 仅当它是之前所有较长字符串的子字符串时才可以，这只有在字符串结构以非常强的方式嵌套时才有可能。 

当最终最大字符串中不包含字符串时，会发生具体的失败情况。 例如，如果我们有`"abc"`和`"b"`，还有`"abd"`， 然后`"abc"`和`"abd"`不能同时包含`"b"`如果没有仔细选择排序，则以一致的方式进行，但真正的障碍是没有一个字符串可以作为所有其他字符串的通用容器。 

第二种微妙的情况是纯粹按长度排序。 如果我们按长度排序并假设较长的字符串总是包含较短的字符串，那么我们会在以下情况下失败`"ab"`和`"cd"`，其中两个都不是另一个的子串。 这会产生一个排序，但违反了条件。 

## 方法

 暴力破解的想法很简单：尝试字符串的所有排列，并检查每个排序是否满足子字符串条件。 对于给定的排列，我们通过检查当前字符串内所有早期字符串的子字符串成员身份来验证每个前缀。 每次排列的验证成本为 O(n² · L)。 因为有 n! 即使对于 n = 10，这也很快变得不可行。 

关键的观察是，这种情况强加了一个强大的全球结构。 如果存在排序，则最后一个字符串必须包含所有其他字符串作为子字符串。 这是因为它之前的所有内容都必须包含在其中。 这意味着最后一个字符串是一个通用容器。 

一旦我们确定了这一点，问题就简化为选择最后一个位置的候选者并检查它是否包含所有其他字符串。 如果存在这样的候选者，我们可以安全地将其放在最后，然后按照与包含一致的顺序对剩余字符串进行任意排序，这可以通过按长度排序并沿途验证子字符串约束来实现。 在实践中，通过增加长度进行排序是有效的，因为任何有效的解决方案都必须具有不减少的长度以满足包含约束，并且验证可确保正确性。 

这将搜索从阶乘减少为最大有效“容器”字符串的简单线性扫描，然后是排序步骤和验证。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（所有排列）| O(n!·n²·L) | O(n!·n²·L) | O(nL) | 太慢了 |
 | 最优（候选+排序+验证）| O(n²·L log n) | O(n²·L log n) | O(nL) | 已接受 |

 ## 算法演练

 我们通过识别可以作为最终元素的字符串来构建解决方案。 

1. 将所有字符串按长度非降序排序。 这使得更容易推理包含，因为较短的字符串更有可能出现在较长的字符串内。 
2. 对于列表中的每个字符串，将其视为最后一个位置的候选字符串。 这样做的原因是最后一个字符串必须包含所有其他字符串作为子字符串，因此只需全局检查它。 
3. 对于选定的候选字符串，验证所有其他字符串都是其子字符串。 如果有一个不是，则丢弃该候选人。 这个检查是核心的可行性测试。 
4. 找到有效候选者后，通过采用所有其他字符串并将它们排序在其前面来构建答案。 我们按长度对这些剩余的字符串进行排序，这确保如果存在有效的嵌套结构，我们不会违反任何潜在的包含依赖性。 
5. 输出由已排序的剩余字符串组成的排序，后跟有效候选字符串。 

如果没有候选人通过遏制测试，我们就得出结论，不存在有效的排序。 

### 为什么它有效

 在任何有效的排序中，最后一个字符串必须包含所有其他字符串作为子字符串，因为每个较早的字符串都必须是它的子字符串。 这使得最后一个元素可以唯一地识别为集合的通用超串。 

一旦这样的字符串在末尾被固定，所有剩余的字符串就保证是它的子字符串。 按长度对剩余字符串进行排序可以保持从较小子字符串到较大子字符串的安全进展，并且由于每个字符串都针对候选字符串进行验证，因此不会发生无效放置。 这保证了构造的排序满足前缀子串条件。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_sub(a, b):
    return a in b

n = int(input())
s = [input().strip() for _ in range(n)]

s.sort(key=len)

for i in range(n):
    ok = True
    for j in range(n):
        if i == j:
            continue
        if s[j] not in s[i]:
            ok = False
            break
    if not ok:
        continue

    other = [s[j] for j in range(n) if j != i]
    other.sort(key=len)

    print("YES")
    for x in other:
        print(x)
    print(s[i])
    sys.exit()

print("NO")
```该代码首先按长度对字符串进行排序，以减少等效情况的不必要的排列。 主循环尝试将每个字符串作为最终候选。 对于每个候选者，它使用 Python 的子字符串操作检查包含性，该操作在给定小约束的情况下高效运行。 

一旦找到有效的候选者，所有其他字符串都会按长度排序并在其之前打印。 这确保了稳定的结构，其中较小的字符串较早出现，并且所有字符串都保证是最终字符串的子字符串。 

提前退出确保我们只输出一个有效的排序。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from __main__ import solve
    return solve()

def solve():
    input = sys.stdin.readline
    n = int(input())
    s = [input().strip() for _ in range(n)]
    s.sort(key=len)

        ok = True
        for j in range(n):

                break

        other.sort(key=len)
        return "YES\n" + "\n".join(other + [s[i]])
    return "NO"

 ## 边缘情况

 一种重要的边缘情况是所有字符串都相同。 在这种情况下，每个字符串都是每个其他字符串的子字符串。 该算法选择任何候选者作为最终字符串。 例如，与`"aaa", "aaa", "aaa"`，每个候选者都通过了遏制测试，其余的排序是任意的。 按长度排序使它们保持不变，并且输出仍然有效。 

另一种情况是只有一个字符串时。 循环选择它作为候选者，并且由于没有其他字符串要检查，因此它立即通过。 输出只是那个字符串，它空洞地满足条件。 

一个更具说明性的情况是当字符串形成严格的链时，例如`"a"`,`"ab"`,`"abc"`。 最长的字符串`"abc"`是唯一有效的候选者，因为它包含所有其他候选者。 该算法将其识别为最后一个元素，将其余两个排序为`"a", "ab"`，并输出正确的排序。
