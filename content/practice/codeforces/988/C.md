 ## 解决方案
 ## 问题理解

 我们有几个独立的整数数组。 我们可以从每个数组中删除一个元素，这会为该数组创建一个“修改后的总和”，这意味着原始总和减去删除的元素。 任务是选择两个不同的数组，并在每个数组中选择一个删除位置，以使修改后的总和相等。 

以更结构化的方式重新表述，对于每个序列，我们可以计算其总和，并且其中的每个元素定义一个通过从总数中减去该元素获得的候选值。 问题简化为找到两个可以产生相同候选值的序列。 

约束以非常具体的方式严格。 所有序列的元素总数最多为 200,000 个，并且最多可以有 200,000 个序列。 任何试图直接比较每对序列的解决方案都需要序列数量的二次行为，这远远超出了可行的限制。 甚至每个序列的二次运算也是不允许的，因为总长度很大。 这促使我们对所有元素采用线性或近线性聚合策略。 

一个幼稚的陷阱来自于将问题视为“通过独立比较所有可能的删除来匹配两个序列”。 例如，如果我们为每个序列生成所有删除后的总和，然后尝试全局匹配它们，我们可能会忘记相同的目标总和可以在单个序列中出现多次，并且我们必须确保两个选定的删除来自不同的序列。 

如果我们仅存储每个序列的最佳删除或仅考虑每个序列的唯一总和，则会发生另一种微妙的失败情况。 像这样的序列`[1, 1, 1]`多次产生相同的候选和，忽略重数可以消除有效匹配。 

## 方法

 暴力破解的想法很简单：对于每个序列，尝试删除每个元素并计算结果总和，然后比较所有序列对及其所有可能的删除。 如果我们用 N 表示总元素，则每个序列贡献 O(n_i) 个候选者，因此总体上有 O(N) 个候选者，但在最坏的情况下，将它们跨序列配对会导致 O(N^2) 次比较。 

从概念上讲，这是可行的，因为每个有效答案都必须出现在这组完整的“删除一个元素后的总和”值中的某个位置。 失败点在于规模：对于 200,000 个元素，二次比较产生大约 10^10 次运算。 

关键的观察是每个候选完全由两个值决定：序列和 S 和删除的元素 a，产生值 S − a。 我们可以一一处理元素并尝试全局检测这些值的冲突，而不是扩展所有候选值。 

我们维护一个从“删除后的目标总和”到生成它的第一对（序列索引，元素索引）的哈希映射。 一旦不同序列中第二次出现相同的目标，我们立即得到一个有效的答案。 

这将问题转化为对所有元素进行单次传递，并对每个元素进行恒定时间散列。

 | 蛮力 | O(N^2) | O(N^2) | O(N) | 太慢了 |

 ## 算法演练

 如果将每个元素删除，我们将其视为定义潜在的“结果总和”。 

### 步骤

 1. 计算每个序列的总和。 

这是必需的，因为每个候选值都取决于从其序列和中减去一个元素。 
2. 对于每个序列 i 和位置 x 处的每个元素 a，计算值：

 S_i − a。 

这表示删除该元素后剩余的总和。 
3. 维护一个哈希映射，其中键是该计算值，该值存储一对 (i, x)，描述哪个序列和哪个索引首先生成它。 

我们只存储第一次出现的情况，因为我们只需要检测碰撞。 
4. 在迭代时，如果我们计算映射中已经存在的值，并且它来自不同的序列，我们会立即返回两个存储的位置。 

这保证了我们发现两个不同的序列产生相同的减少的总和。 
5. 如果处理完所有元素后没有发现碰撞，则输出NO。 

### 为什么它有效

 每个有效解对应一个值 V，使得存在两个序列 i 和 j，以及 i 中的元素 x 和 j 中的 y 满足 S_i − a[i][x] = S_j − a[j][y]。 我们的地图存储每一个见过的对（V→第一次出现）。 当另一个序列中第一次出现重复的 V 时，我们就完全具有所需的相等性。 由于我们只处理一次所有可能的删除，因此不会错过任何有效答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input())
    
    seq = []
    total = []
    
    for i in range(k):
        n = int(input())
        arr = list(map(int, input().split()))
        seq.append(arr)
        total.append(sum(arr))
    
    seen = {}
    
    for i in range(k):
        arr = seq[i]
        S = total[i]
        for j, val in enumerate(arr):
            key = S - val
            if key in seen:
                pi, pj = seen[key]
                if pi != i:
                    print("YES")
                    print(pi + 1, pj + 1)
                    print(i + 1, j + 1)
                    return
            else:
                seen[key] = (i, j)
    
    print("NO")

if __name__ == "__main__":
    solve()
```该解决方案首先读取所有序列并预先计算它们的总和，因为重复的总和计算会增加复杂性。 然后，主逻辑对每个元素进行一次迭代，计算候选缩减总和。 

哈希图`seen`存储每个候选值的第一次出现。 当不同序列中出现重复项时，我们立即输出这两个位置。 索引检查确保我们永远不会将一个元素与同一序列中的另一个元素进行匹配，这将违反选择两个不同序列的要求。 

一个微妙的实现细节是在内部存储从零开始的索引，但打印从一开始的索引，因为问题需要从 1 开始的输出。

 ## 边缘情况

 关键的边缘情况是同一序列中的多个元素生成相同的候选和。 例如，`[1, 1, 1]`产生相同的减少总和三次。 该算法仅存储第一次出现的情况，但仍处理后来的重复项，确保它们可以在需要时与其他序列进行匹配。 

另一种情况是当唯一的冲突发生在单个序列内时。 考虑`[2,2]`和`[1,3]`。 值 2 在第一个序列中出现两次，但这并不形成有效答案。 支票`pi != i`防止误报。 

最后一种情况是序列很大但不存在匹配项。 该算法仍然在没有早期假设的情况下执行完整的线性扫描，并且哈希图仍然受 O(N) 限制，即使在最坏情况的输入中也确保了可预测的行为。
