 ## 解决方案

 ## 问题理解

 我们得到了一组放置在数轴上的不同点。 任务是选择尽可能多的点，但具有非常强的几何限制：每对选定点的距离必须恰好是 2 的幂。 

换言之，如果我们选择一个子集，那么对于任意两个选定的位置$a$和$b$，值$|a-b|$必须属于集合$\{1,2,4,8,16,\dots\}$。 该条件在子集中是全局的，这意味着它不仅必须适用于按排序顺序的相邻点，而且必须适用于所有点对。 

输出不仅是子集的大小，而且是实际选择的坐标。 

约束条件$n \le 2 \cdot 10^5$排除任何重复检查所有子集甚至子集中所有对的解决方案。 任何与$n$已经很挣扎了，任何指数级的事情都是不可能的。 

微妙的一点是，条件极其严格。 特别是，在某些排序中，点间隔为 2 的幂是不够的。 有效的子集必须形成一个结构，其中所有成对距离都属于同一乘法族的二的幂，这强烈限制了可能的配置。 

一种失败模式来自于仅考虑连续差异。 例如，如果我们取点$3, 5, 7$，连续的差值是$2$和$2$，都是 2 的幂，但是距离$7 - 3 = 4$也是二的幂，所以这有效。 然而，如果我们尝试$3, 5, 9$，连续差异为$2$和$4$，单独来看都很好，但是成对的$9 - 3 = 6$即使本地检查会通过，也会破坏条件。 

另一个常见的陷阱是假设子集必须形成算术级数或几何结构等模式。 条件不要求间距均匀； 它只限制所有成对差异，这更多是组合性的而不是顺序性的。 

## 方法

 蛮力的想法很简单：尝试每个子集并检查它是否满足条件。 对于每个子集，我们对其元素进行排序并验证所有成对差异。 这是正确的，但立即不可行，因为子集的数量是$2^n$，甚至检查一个子集成本$O(k^2)$。 

一个更有用的起点是将问题视为构建一个图，其中顶点是点，如果两点的距离是 2 的幂，则两点之间存在一条边。 任务变成找到该图中最大的派系。 

这种重新表述很有帮助，因为派系已得到充分研究，但这里的图结构非常结构化：边仅存在于非常特定的距离处，而这些距离是 2 的幂。 这种结构可以防止任意密集图的出现。 

关键的观察结果是，大派系极为罕见。 如果我们对点进行排序，我们可以考虑固定子集的最小元素。 假设最小的选择点是$x$。 然后所有其他选定的点必须位于一定距离$2^k$从$x$，但这些点之间的所有成对差值仍必须是 2 的幂。 这严重限制了集合：一旦我们选择了几个点，它们之间的所有差异都必须位于一个非常小的、结构化的集合中。 

关键的简化是，任何有效的最佳子集都必须包含最大扩展很小的“基本配置”，我们可以尝试在每个点锚定解决方案，并仅贪婪地扩展到保持所有成对差异有效的位置。 由于有效结构不能很大且任意，因此对于每个起点，我们只需要探索距离二次方距离的少量候选点。 

这导致了一个解决方案，我们尝试将每个点作为潜在的锚点，并且仅测试距离为 2 的幂的点。 此类距离的数量大约为 31（因为值适合 32 位范围）。 对于每个锚点，我们收集通过这些偏移量可到达的候选点，然后验证完整的子集。 

重要的隐藏结构是，如果存在一个大的有效子集，那么它的所有点都必须位于通过重复从基点添加或减去 2 的幂而生成的集合内。 该结构足够稀疏，可以有效地进行枚举。

 ## 算法演练

 我们假设积分存储在一组中，以便快速进行会员资格检查。 

1. 将所有点插入到哈希集中，以便我们可以测试是否存在$O(1)$。 这是必要的，因为所有候选构造都依赖于检查生成的值是否实际存在于输入中。 
2. 迭代每个点$x$作为答案的可能的起始锚点。 这个想法是，任何最佳子集都有一个最小的元素，并且尝试所有锚点可以保证我们不会错过它。 
3.对于每个锚点$x$，构造一个候选子集，从$\{x\}$。 
4. 对于每个功率$2^k$达到合理的限制（足够大，以便$x + 2^k$保持在坐标范围内），检查是否$x + 2^k$存在于集合中。 如果是，则暂时考虑将其添加到子集中。 
5. 收集完该锚点的所有候选者后，我们对它们进行排序。 需要排序是因为成对条件取决于所有差异，而不仅仅是距锚点的距离。 
6. 通过检查所有成对差异来验证候选子集。 如果所有差异都是 2 的幂，我们将其大小与迄今为止的最佳答案进行比较。 

验证步骤是必不可少的，因为来自锚点的贪婪构造仍然可能产生无效的子集； 它只生成候选者，不保证正确性。 

### 为什么它有效

 任何有效子集都必须有一个最小元素$x$。 所有其他元素都位于距离$x$，并且由于所有成对差异必须是 2 的幂，因此这些点必须与通过以一致的方式添加两个偏移量的幂生成的结构对齐。 通过枚举所有锚点和所有二次方偏移量，我们确保任何有效配置都完全包含在至少一个候选集中。 最后的验证步骤会过滤掉意外的无效组合，只留下真正的派系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def is_power_of_two(x):
    return x > 0 and (x & (x - 1)) == 0

def valid(arr):
    m = len(arr)
    for i in range(m):
        for j in range(i + 1, m):
            if not is_power_of_two(abs(arr[i] - arr[j])):
                return False
    return True

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    s = set(a)

    best = []

    # precompute powers of two up to coordinate range
    pw = [1 << i for i in range(32)]

    for x in a:
        cand = {x}

        for p in pw:
            y = x + p
            if y in s:
                cand.add(y)

        cand = list(cand)
        if len(cand) <= len(best):
            continue

        cand.sort()
        if valid(cand):
            best = cand

    print(len(best))
    print(*best)

if __name__ == "__main__":
    solve()
```该代码构建了所有坐标的哈希集，以便检查潜在点是否存在的时间是恒定的。 对于每个锚点，它仅尝试添加距离为 2 的幂的点，这反映了在涉及该锚点的有效配置中可能出现的唯一距离。 

验证函数显式检查所有成对距离。 尽管是二次的，但它仅在小型候选集上运行，这使其足够快。 

关键的实施决策是限制候选人$x + 2^k$。 这编码了结构约束，即任何有效配置必须与参考点的二次方间隙一致。

 ## 边缘情况

 关键的边缘情况是所有点都非常接近，例如连续整数。 该算法仍然只形成小的候选集，因为只考虑两个精确幂的差异，从而防止意外的全选择。 

另一种边缘情况是当点稀疏但按 2 的幂对齐时，例如$0, 8, 16, 24$。 尽管许多差异是 2 的幂，但像 16 和 24 这样的交叉差异会创建不是 2 的幂的值，并且验证步骤会拒绝不正确的扩展，同时仍然允许正确的子集。 

基于锚的构造确保从最小元素开始发现每个有效配置，而验证步骤则保证没有无效结构幸存。
