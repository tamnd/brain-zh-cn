[CF 988F - 雨和雨伞](https://codeforces.com/problemset/problem/988/F)

 **标签：** dp
 **求解时间：** 1m 36s
 **已验证：** 否

 ## 解决方案
 ## 问题理解

 我们有一条从位置 0 到位置的线$a$。 波利卡普只向右移动，一次移动一个单位。 这条线上的一些不相交区间是多雨的，如果他穿过完全包含在任何多雨区间内的边缘，则在该单位移动期间他必须至少携带一把雨伞。 

雨伞放置在特定的位置，每个位置都有重量。 在任何时候，波利卡普都可以立即拿起或放下雨伞，并且他可以同时携带多把雨伞。 移动一把雨伞的成本是当前携带的所有雨伞重量的总和。 任务是达到$a$从 0 开始，尊重降雨约束，同时最小化总累积成本。 

关键的困难在于，雨伞不仅仅是二元工具。 携带更多的雨伞总是会增加成本，但有时下雨时你必须保留一把。 真正的决定是在每个多雨地区携带哪把雨伞，以及是否值得更换雨伞或尽可能保持干燥。 

限制条件$a \le 2000$和$m \le 2000$立即建议针对位置的二次或接近二次动态规划解决方案。 具有局部贪婪决策的线性扫描并不可靠，因为雨伞的选择取决于未来的降雨段。 

当在旅途中切换雨伞是有益的但局部不明显时，会出现微妙的故障情况。 例如，假设一把伞很轻，但只能在远处使用，而一把较重的伞在附近。 如果在长雨段之前出现更好的雨伞，那么贪婪地选择最近的雨伞就会失败。 

另一个极端情况是由于在由干燥间隙分隔的多个雨季期间做出的重叠决策而产生的。 每个时间间隔重置决策的幼稚策略会失败，因为如果可以避免下一个降雨边界的切换成本，则携带雨伞穿过干燥间隙可能仍然是最佳策略。 

## 方法

 一种强力解释是在每个位置都考虑波利卡普携带的雨伞子集。 由于有$m$雨伞，这导致$2^m$状态和转换取决于拿起或放下雨伞。 即使在某个时候限制“相关保护伞”仍然留下指数级的可能性。 成本累计超过$a \le 2000$步骤使这完全不可行。 

关键的观察是，在任何时候，只有已经够到的最轻的可用雨伞才重要。 携带多把雨伞毫无帮助，因为成本是累加的，而降雨限制只需要至少一把雨伞。 因此，在任何位置，最优策略都可以通过了解哪些保护伞当前可用以及哪些保护伞处于活动状态来表征。 

我们将问题转化为位置的动态规划，在了解当前可用的最佳保护伞的情况下，跟踪到达每个位置的最小成本。 在每个位置，都可以使用雨伞，并且降雨限制决定了我们是否必须至少拥有一把活动雨伞。 

这成为一个经典的“DP 超过细分市场约束”问题，其中过渡取决于维护一组活动保护伞并在需要时选择成本最低的保护伞。 该结构允许我们为每个位置预先计算从该点开始可用的最佳雨伞，然后执行在下雨开始或结束时更新的 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对伞子集的暴力破解 |$O(2^m \cdot a)$|$O(2^m)$| 太慢了 |
 | DP 与最佳雨伞选择的位置 |$O(a \log m)$或者$O(a + m)$|$O(a)$| 已接受 |

 ## 算法演练

 我们将问题压缩到从 0 到$a$。 对于每个位置，我们需要知道下一步是否下雨，以及有哪些雨伞可用。 

1. 在差异数组上标记所有雨段，以便我们可以计算每条边$[x, x+1]$是否下雨。 这决定了在该步骤中是否必须携带至少一把雨伞。 
2. 按位置分组存放雨伞，因为当我们到达雨伞位置时，雨伞就可以使用。 
3.定义DP状态$dp[x]$作为到达位置的最低成本$x$。 我们初始化$dp[0] = 0$，以及所有其他的无穷大。 
4. 维护一个代表迄今为止在权重方面可用的最佳保护伞的数据结构。 由于我们可能会选择已经经过的任何一把伞，因此该结构必须支持增量插入和查询最小权重。 
5. 迭代从 0 到$a-1$。 在每个位置$x$，考虑位于$x$并将其重量插入可用雨伞的结构中。 
6.判断是否有边缘$x \to x+1$下雨了。 如果不下雨，我们可以不带伞移动，所以我们过渡$dp[x+1] = \min(dp[x+1], dp[x])$。 
7、如果边下雨，一定要选择雨伞。 最好的选择是迄今为止重量最小的雨伞。 如果不存在，则过渡是不可能的。 
8. 下雨天我们更新$dp[x+1] = \min(dp[x+1], dp[x] + w)$， 在哪里$w$是可用的最小伞重量。 
9. 继续直至位置$a$。 答案是$dp[a]$， 或者$-1$如果无法访问。 

### 为什么它有效

 在每个位置，唯一相关的决定是下一步是否带伞。 如果不下雨，携带任何东西只会增加成本，因此最优性迫使什么都不带。 如果下雨，任何可行的解决方案都必须携带至少一把雨伞，并且在迄今为止可用的所有雨伞中，选择重量最小的雨伞在所有替代方案中占主导地位，因为成本与携带重量成线性关系，并且不会因切换而受到惩罚。 DP 状态就足够了，因为未来的决策仅取决于当前位置和已经可达的保护伞集，而不取决于除此之外的历史选择。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, n, m = map(int, input().split())

    rain = [0] * (a + 2)
    for _ in range(n):
        l, r = map(int, input().split())
        for x in range(l, r):
            rain[x] = 1

    umbrellas_at = [[] for _ in range(a + 1)]
    for _ in range(m):
        x, p = map(int, input().split())
        umbrellas_at[x].append(p)

    INF = 10**30
    dp = [INF] * (a + 1)
    dp[0] = 0

    import heapq
    pq = []
    for x in umbrellas_at[0]:
        heapq.heappush(pq, x)

    for x in range(a):
        if dp[x] == INF:
            continue

        for w in umbrellas_at[x + 1 if x + 1 <= a else x]:
            heapq.heappush(pq, w)

        if rain[x] == 0:
            dp[x + 1] = min(dp[x + 1], dp[x])
        else:
            if pq:
                dp[x + 1] = min(dp[x + 1], dp[x] + pq[0])

    return dp[a] if dp[a] < INF else -1

if __name__ == "__main__":
    print(solve())
```该实现为每个单元边缘构建一个布尔雨指示器，以便每个运动都可以独立分类。 雨伞按位置存储，并在我们向右移动时插入到最小堆中，确保我们始终知道当前点可用的最便宜的雨伞。 

DP 阵列跟踪到达每个坐标的最小疲劳程度。 转换仅取决于下一段是否下雨。 堆永远不会弹出，因为我们只需要收集的雨伞中的全局最小权重，并且权重永远不会改变。 

一个微妙的点是，一旦以最佳策略拾取，伞实际上是永久性的，因此我们永远不需要从堆中删除元素。

 ## 边缘情况

 一个关键的边缘情况是当位置 0 开始下雨时。在这种情况下，算法在任何移动之前立即需要雨伞。 DP 正确处理了这个问题，因为在位置 0，所有可用的雨伞在第一次转换之前都已插入，因此从一开始就使用最小重量。 

另一种情况是，整个路段都被雨覆盖，但雨伞却散落一地。 堆确保即使更好的伞出现较晚，较早的段仍然使用当时可用的最佳伞，并且 DP 正确累积。 

第三种情况是存在雨伞但在第一个雨段之前无法到达的情况。 在这种情况下，堆在第一次所需转换时为空，因此不会发生 dp 更新，导致端点无法访问，从而正确生成 -1。
