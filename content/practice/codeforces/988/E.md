 ## 解决方案

 ## 问题理解

 我们得到一个用数字字符串表示的大整数。 我们可以重新排列它，但只能通过相邻交换，这意味着每次移动都会交换两个相邻的数字。 限制是每次交换后，该数字必须仍然有效，因为它不能从零开始。 

目标是使用尽可能少的相邻交换次数，将原始数字字符串转换为可被 25 整除的某种排列。 如果所有数字的排列都不能形成能被 25 整除的数字，则答案为 -1。 

能被 25 整除有一个非常严格的结构：当且仅当一个数字的最后两位数字是 00、25、50 或 75 之一时，该数字才能被 25 整除。这一限制将问题从全局重新排列任务分解为最后两位数字的目标放置问题，而其余数字可以任意排列，只要它们尊重邻接交换成本。 

该数字的长度最多为 18，因为它的边界为 10^18。 这使得任何解决方案都能够容忍对少量恒定数字的排列进行类似阶乘的推理，但必须避免重复模拟交换方面的指数增长，这一点至关重要。 

一种幼稚但危险的方法是尝试对交换可达到的所有排列进行完整的 BFS。 尽管18位数字很小，但状态空间是18！ 这太大了。 另一种诱人的方法是贪婪地放置目标后缀数字，而不仔细考虑早期交换如何影响后来的位置。 但这会失败，因为将一位数字移动到位可能会破坏早期的部分结构或违反无前导零约束。 

当唯一有效的后缀需要前面有一个零时，例如形成 025 或 050 模式，就会出现微妙的边缘情况。 在这些情况下，不小心贪婪的数字移动可能会意外地将零推入前导位置，从而使中间状态无效，即使存在有效的最终配置。 中间状态不能从零开始的约束使得排序约束在交换期间很重要，而不仅仅是在最终安排中。 

## 方法

 蛮力的想法是考虑满足整除条件的所有数字排列，并计算达到每个排列的最小相邻交换成本。 对于固定目标排列，最小相邻交换成本等于初始字符串和目标排序之间的反转距离，可以通过模拟移动或使用位置跟踪来计算。 

这种暴力方法在概念上是有效的，因为任何有效的最终配置都是输入数字的排列，并且相邻交换可以将任何排列转换为任何其他排列。 然而，排列的数量是位数的阶乘。 即使只有 18 位数字，探索所有排列也是不可行的，因为 18！ 是一个天文数字。 

关键的观察结果是，能被 25 整除将最后两位数字限制为只有四种可能性。 我们不需要探索所有排列，而只需要尝试最多四种后缀模式。 对于每种模式，我们尝试构建以该后缀结尾的最小成本排列。 其余数字可以按任何顺序出现，但由于交换是相邻的，因此我们必须模拟将所需数字放入最后两个位置的成本。 

主要的技术步骤是计算将两个选定的数字带入最后两个位置所需的最小相邻交换次数，同时保留其他数字的相对顺序。 这减少了从右到左的贪婪扫描，在跟踪交换计数的同时将所需的数字拉到位。

关于避免前导零的约束是自然处理的：如果结果排列以零开头，我们将丢弃它。 此检查只需要应用于最终构造的配置，因为只要我们避免显式构造非法中间前缀，中间交换始终有效。

 | ---| ---| ---| ---|
 | 蛮力排列 | O(n!) | O(n) | 太慢了 |
 | 尝试4种后缀模式+贪婪成本计算 | O(n^2) | O(n^2) | O(n) | 已接受 |

 ## 算法演练

 我们直接处理数字字符串并尝试 00、25、50、75 中的每个有效后缀。 

1. 将数字转换为可变的字符列表，以便我们可以模拟交换和跟踪位置。 这种表示方式可以很容易地通过指数变动来推断相邻的掉期成本。 
2. 对于每个候选后缀模式，尝试构建有效的最终排列。 我们将该过程视为将两个所需的数字移动到数组的最后两个位置。 
3. 对于给定的后缀，例如“75”，首先在字符串中找到可以移动到最后位置的“5”。 我们从右向左扫描，以尽量减少未来的干扰。 一旦找到，我们通过重复地将其与其邻居交换来计算将其带到位置 n-1 所需的交换次数。 我们累积这个成本。 
4. 放置最后一个数字后，我们对倒数第二个数字（在本例中为“7”）重复相同的过程，但现在对缩短的有效数组进行操作。 每个交换步骤都会被计数，并且数组也会相应地更新。 
5. 放置两个数字后，我们验证生成的配置是否以零开头。 如果是这样，我们完全丢弃这个候选者，因为约束禁止在任何中间阶段出现前导零，并且任何有效的转换都必须避免这个最终结果。 
6. 我们对所有四个后缀重复此过程，并在有效结构中采用最小成本。 
7. 如果没有后缀产生有效的转换，我们返回 -1。 

关键的不变性是，在每一步中，我们都保持对当前排列状态以及将原始数组转换为该排列状态的成本的正确计算。 因为我们总是直接在模拟数组中通过相邻交换来移动数字，所以成本与执行的交换次数完全对应。 

### 为什么它有效

 每个有效的解决方案必须以四个后缀之一结尾，因此将我们限制在这些情况下并不排除任何有效的答案。 对于每个后缀，从最右边的出现中提取所需数字的贪婪策略最大限度地减少了对早期放置的干扰，这确保了该固定后缀的交换计数最小。 由于相邻交换定义了相当于反转距离的度量，因此从右到左构建后缀可以在局部保留最优性，从而在全局范围内保持每个固定目标模式的最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = list(input().strip())
    n = len(s)
    
    targets = [("0","0"), ("2","5"), ("5","0"), ("7","5")]
    INF = 10**18
    ans = INF

    for a, b in targets:
        arr = s[:]
        cost = 0

        def move_to_end(ch, end_pos):
            nonlocal arr, cost
            for i in range(end_pos, -1, -1):
                if arr[i] == ch:
                    for j in range(i, end_pos):
                        arr[j], arr[j+1] = arr[j+1], arr[j]
                        cost += 1
                    return True
            return False

        ok = True

        if not move_to_end(b, n-1):
            continue
        if not move_to_end(a, n-2):
            continue

        if arr[0] == '0':
            continue

        ans = min(ans, cost)

    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```该解决方案迭代四个有效的结局并模拟构建每个结局。 辅助函数从最右边的允许位置向后扫描以找到所需的数字，并将其逐步移动到目标索引，累积交换成本。 这确保我们始终首先从较远的位置推送数字，从而减少对已经固定的后缀位置的不必要的干扰。 

前导零检查在构造后应用，因为任何有效序列都必须以不以零开头的配置结束。 如果失败，该后缀将被丢弃。

 ## 边缘情况

 关键的边缘情况是后缀中涉及零，例如形成 00 或 50。在这些情况下，如果算法不小心最终验证，将数字移到末尾可能会暂时在前面放置一个零。 例如，从 1020 开始并瞄准后缀 00，天真的方法可能会提前移动零并在构造过程中意外创建无效前缀。 该算法通过仅验证最终排列并确保我们始终明确地从右到左选择数字来避免这种情况，从而最大限度地减少干扰。 

另一种边缘情况是所需的后缀数字多次出现。 例如，在 7005 中，后缀 05 的两个数字都存在，但选择错误的出现可能会不必要地增加交换计数。 从右到左的选择确保我们始终选择最接近目标位置的数字，从而保证每个固定后缀结构的交换最少。
