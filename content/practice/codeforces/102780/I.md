 # 问题理解

 我们有一个包含所有整数点的方形网格`(1, 1)`到`(n, n)`。 其中一点是隐藏的。 程序不知道它的坐标，但它可以向法官询问几何问题。 查询可以测试单个点、线段或三角形，判断器会回答隐藏点是否属于该对象。 

目标是使用最多 60 个查询来识别隐藏点。 输入仅给出`n`，可以大到`10^8`，因此迭代网格是不可能的。 输出是发现点的坐标。 

网格的大小是主要限制。 一个正方形有边长`n`包含多达`10^16`可能的头寸，因此即使检查一百万个头寸也不够。 查询限制告诉我们每个问题都必须删除剩余可能性中的很大一部分。 自从`log2(10^8)`大约是 27，二分搜索风格的方法是很自然的，因为对坐标的两次独立搜索可以轻松地容纳 60 个查询。 

一个常见的错误是尝试通过询问该点是在垂直线的左侧还是右侧来对 x 坐标进行二分搜索。 可用的查询不直接支持半平面，因此不能使用简单的矩形查询来实现。 另一个错误是忘记隐藏点可以位于正方形的边界上。 任何几何构造都必须包含边界点，因为排除边缘的查询可能会永久丢失答案。 

例如，当`n = 3`, 点`(1, 2)`是有效的。 意外地将正方形视为开放区域的查询`(1, 3) x (1, 3)`会错过它并且永远无法找到答案。 

最小情况是`n = 1`。 唯一可能的答案是`(1, 1)`，假设存在两个不同坐标的解决方案将创建无效查询。 

# 方法

 蛮力方法很简单。 我们可以对每个网格点进行类型 1 查询，直到法官回答“是”。 这是正确的，因为每个可能的位置都会被检查，但最坏的情况需要`n^2`查询。 为了`n = 10^8`， 这意味着`10^16`查询次数，远远超出允许的 60 条。 

有用的观察是三角形查询的表达能力足以执行二分搜索。 可以构建一个非常大的三角形，以便在原始正方形内它的行为就像垂直或水平切割。 这允许我们重复丢弃剩余坐标范围的一半。 

搜索执行两次。 首先我们定位 x 坐标，然后定位 y 坐标。 在每次搜索期间，当前间隔被保存为一组可能的整数坐标。 三角形查询告诉我们隐藏点是否在该区间的一半内，因此每次区间大小都会除以二。 

这样做的原因是坐标限制。 单个坐标最多有`10^8`可能性，最多需要 27 个二元决策。 查找两个坐标所需的查询次数少于 54 次，剩下额外的查询用于最终点确认。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) 查询 | O(1) | O(1) | 太慢了 |
 | 最佳| O(log n) 次查询 | O(1) | O(1) | 已接受 |

 # 算法演练

 1. 阅读`n`。 可能的 x 和 y 坐标都在区间内`[1, n]`。 
2. 对 x 坐标进行二分查找。 对于中点`m`，询问一个代表正方形一半的三角形查询`x <= m`。 如果答案是肯定的，则隐藏点最多有x坐标`m`，所以区间的右边界变为`m`。 否则左边框变成`m + 1`。 

用于此查询的三角形有一个非常大的第三个顶点。 因为所有有效点最多有坐标`n`，斜边几乎是垂直的，因此三角形恰好包含原始正方形的预期一半。 

1. 对 y 坐标重复相同的二分查找。 使用相同结构的旋转版本来询问是否`y <= m`。 
2. 知道两个坐标后，输出它们作为最终答案。 

为什么它有效：

 在每次二分搜索迭代中，查询将当前可能的坐标集分为两部分。 判断答案告诉我们哪个部分包含隐藏点，因此保留了不变量：每次查询后，真实位置仍保留在维护的区间内。 当间隔长度变为 1 时，只剩下一个坐标。 对 x 和 y 独立执行此操作可以唯一地确定隐藏点。 

# Python 解决方案```python
import sys

input = sys.stdin.readline

def ask_triangle(a, b, c):
    print("? 3", a[0], a[1], b[0], b[1], c[0], c[1], flush=True)
    return input().strip() == "Yes"

def ask_point(x, y):
    print("? 1", x, y, flush=True)
    return input().strip() == "Yes"

def find_x(n):
    lo, hi = 1, n
    while lo < hi:
        mid = (lo + hi) // 2
        if ask_triangle((1, 1), (mid, n), (1000000000, 1)):
            hi = mid
        else:
            lo = mid + 1
    return lo

def find_y(n):
    lo, hi = 1, n
    while lo < hi:
        mid = (lo + hi) // 2
        if ask_triangle((1, 1), (n, mid), (1, 1000000000)):
            hi = mid
        else:
            lo = mid + 1
    return lo

def solve():
    n = int(input())
    if n == 1:
        print("! 1 1", flush=True)
        return

    x = find_x(n)
    y = find_y(n)

    ask_point(x, y)
    print("!", x, y, flush=True)

if __name__ == "__main__":
    solve()
```辅助函数隔离了交互协议。 将所有刷新保留在这些函数内可以避免意外缓冲查询并永远等待答案。 

x 搜索维护可能的 x 坐标的区间。 三角形`(1,1), (mid,n), (1000000000,1)`选择使得原始正方形中 x 不超过的所有点`mid`都在里面。 非常大的坐标是安全的，因为该语句允许坐标达到`10^9`。 

旋转结构后的 y 搜索是相同的想法。 最终的类型 1 查询只是打印答案之前的确认查询。 

所有坐标都存储为Python整数，因此不存在溢出问题。 间隔更新使用`mid + 1`和`mid`小心，这可以防止二分搜索中的无限循环。

def query_count(n):

 # 边缘情况

 对于`n = 1`，网格仅包含一个可能的隐藏位置。 该算法单独处理这个问题，因为长度为 1 的二分搜索间隔不应生成任何几何查询。 

对于边境的藏品，例如`(1, n)`，三角形查询仍然包括三角形的边，因为成员资格被定义为位于内部或边界上。 二分查找永远不会删除有效的边界坐标。 

对于最大可能的值`n`，二元决策的数量仍然很少。 坐标范围不是线性搜索的，因此即使网格包含，也会遵守查询限制`10^16`可能的点。
