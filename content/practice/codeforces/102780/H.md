 ## 解决方案
 ## 问题理解

 我们有一堆包含 N 支蜡笔。 两名玩家轮流轮流，每轮一名玩家准确取出 1、5 或 13 支蜡笔。 拿走最后一支蜡笔的玩家立即获胜。 两位玩家都知道当前的牌堆大小，并且总是选择能够最大化获胜机会的动作。 任务是确定第一或第二玩家是否有获胜策略。 

输入包含一个整数 N，即蜡笔的初始数量。 输出是能够强行获胜的玩家数量，其中玩家 1 先移动，玩家 2 第二移动。 

N 的上限是 10000。这个值足够小，可以轻松实现线性动态规划解决方案。 尝试每种可能的游戏序列的解决方案将呈指数级增长，因为每个位置最多可以分支到三个下一个位置。 即使是二次方法也是不必要的，因为每个桩尺寸仅取决于几个较小的桩尺寸。 

棘手的情况来自接近比赛结束的位置。 例如，当只有一支蜡笔时：```
1
```正确的输出是：```
1
```玩家可以移除唯一的蜡笔并获胜。 如果粗心的解决方案仅检查玩家是否可以拿走 5 支或 13 支蜡笔，则可能会错误地将其标记为失败。 

另一个边界情况是：```
2
```正确的输出是：```
2
```第一个玩家必须取出一支蜡笔，留下一支给对手。 然后第二个玩家拿走最后一支蜡笔。 仅基于移动大小的天真模式可能会忽略小损失状态是由先前状态决定的。 

## 方法

 直接的方法是模拟每一种可能的游戏。 对于给定数量的蜡笔，我们可以递归地尝试拿 1、5 或 13 支蜡笔，看看是否有任何选择会导致对手失败。 这是正确的，因为每一个可能的行动都被考虑在内，并且当一个玩家能够移动到另一个玩家无法强行获胜的状态时，他就获胜了。 

这种方法的问题是重复状态的数量。 例如，在分析一堆大小为 10000 的桩时，许多不同的移动序列最终都会达到相同的较小桩大小。 在不存储结果的情况下，递归会一次又一次地探索相同的位置。 可能的移动序列的数量大致呈指数级，因此速度太慢。 

关键的观察结果是，只有当前的蜡笔数量才重要。 移动的历史对未来的可能性没有影响。 这意味着每个堆大小都是一个单独的游戏状态，我们只需要知道该状态是赢还是输。 

如果当前玩家可以做出使对手处于失败状态的一步，我们将状态定义为获胜。 否则，国家就会失败。 从最小的堆开始，我们可以计算最多 N 的所有状态。这将递归搜索转换为简单的动态编程过程。 

蛮力方法之所以有效，是因为它探索了每一种可能的未来，但当通过许多不同的路径达到相同的桩尺寸时，它就会失败。 通过观察游戏状态仅取决于蜡笔的剩余数量，我们可以一次性解决每个状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(3^N) | O(3^N) | O(N) 递归深度 | 太慢了 |
 | 最佳| O(N) | O(N) | 已接受 |

 ## 算法演练

 1. 创建一个数组，其中索引 i 处的值表示包含 i 支蜡笔的一堆是否为轮到的玩家获胜。 真值表示当前玩家可以强行获胜，而假值表示每一步最终都会失败。 
2. 将零蜡笔状态设置为丢失。 开始回合时没有蜡笔的玩家无法移动，因此这种状态是基本情况。 
3. 对于从 1 到 N 的每个蜡笔大小，检查三种可能的移动：取出 1、5 或 13 支蜡笔。 如果可以采取行动并给对手留下失败的状态，则将当前状态标记为获胜。 

这样做的原因是玩家只需要一次成功的行动。 如果他们能够让对手处于失败的位置，那么最佳的打法就保证了对手无法避免失败。 

1.计算出N支蜡笔的状态后，如果状态为获胜，则输出玩家1，否则输出玩家2。 

为什么它有效：

 动态规划不变量是，在处理完大小为 i 的蜡笔后，存储的值准确地描述了当剩余 i 支蜡笔时游戏的结果。 基本情况是正确的，因为零蜡笔意味着前一位玩家已经获胜。 对于其他每个状态，算法都会检查所有合法的动作。 如果任何一步棋达到失败状态，则当前玩家选择该步棋即可获胜。 如果不存在这样的走法，则每一种可能的走法都会给对手带来获胜的位置，因此当前的状态是失败。 由于计算状态时所有较小的状态都是已知的，因此每个决策都基于正确的信息。 

## Python 解决方案```python
import sys

input = sys.stdin.readline

def solve():
    n = int(input())
    
    win = [False] * (n + 1)
    
    moves = [1, 5, 13]
    
    for i in range(1, n + 1):
        for move in moves:
            if i >= move and not win[i - move]:
                win[i] = True
                break
    
    print(1 if win[n] else 2)

if __name__ == "__main__":
    solve()
```数组`win`存储从 0 到 N 的每个桩大小的游戏结果。它从所有值设置为失败开始，因为只有在找到达到失败状态的有效移动后，状态才会变为获胜。 

循环按升序处理状态。 计算时`win[i]`, 每个州`win[i - move]`已经有了最终值，因为移动后剩余的一堆总是小于 i。 

这`break`一旦发现获胜动作，语句就会停止检查动作。 无需进一步搜索，因为一个获胜选项就足够了。 边界检查`i >= move`防止访问无效的负索引。 

Python 整数足够大来解决这个问题，并且最大数组大小只有 10001 个元素，因此内存使用量很小。 

## 工作示例

 考虑输入：```
1
```踪迹是：

 | 当前堆大小 | 移动已选中 | 以前的状态 | 赢得价值|
 | ---| ---| ---| ---|
 | 1 | 删除 1 | 赢[0] = 假 | 真实|

 唯一的举动会移除最后一支蜡笔，并让对手留下零支蜡笔。 由于对手没有必胜棋步，因此玩家 1 获胜。 

现在考虑：```
2
```踪迹是：

 | 当前堆大小 | 移动已选中 | 以前的状态 | 赢得价值|
 | ---| ---| ---| ---|
 | 1 | 删除 1 | 赢[0] = 假 | 真实|
 | 2 | 删除 1 | 赢[1] =真| 假|

 对于一堆尺寸为 2 的蜡笔，移除一支蜡笔会给对手带来胜利状态。 取出五支或十三支蜡笔是不可能的。 每一步都输，所以玩家 2 获胜。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(N) | 每个桩大小仅检查三种可能的移动。 |
 | 空间| O(N) | 该数组为每个堆大小存储一个布尔结果。 |

 由于 N 限制为 10000，该算法仅执行几万次操作，并且很容易满足给定的限制。

import io

def solve_input(inp: str) -> str:
    old_stdin = sys.stdin

 ## 边缘情况

 对于一支蜡笔盒：```
1
```该算法开始于`win[0] = False`。 加工时`i = 1`，取出一支蜡笔达到`win[0]`，这对于下一个玩家来说是失败的。 当前状态变为获胜，因此输出为玩家 1。 

对于两支蜡笔的情况：```
2
```第一个玩家只能取出一根蜡笔。 这样就剩下一支蜡笔，并且`win[1]`已经知道是真的。 由于唯一的举动给对手带来胜利状态，`win[2]`保持为 false，输出为玩家 2。 

对于与一个可用的移动完全匹配的一堆：```
13
```状态计算最终达到`i = 13`。 取出十三支蜡笔达到`win[0]`，所以国家获胜。 该算法不需要对移动大小进行特殊处理，因为它们自然包含在转换检查中。 

对于最大输入：```
10000
```该算法仍然只执行 10000 个状态计算，每个状态计算有三种可能的转换。 相同的不变量适用于整个范围，因此计算最终结果时不会出现递归深度问题或过多的计算。```
