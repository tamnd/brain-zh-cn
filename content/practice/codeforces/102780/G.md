 # 问题理解

 我们最多有四个沙漏。 每个沙漏测量一个固定的持续时间，其沙子可以向任一方向流动。 只有当至少一个沙漏变空时，我们才可以翻转沙漏。 第一个动作发生在时间 0，目标是使某个沙漏恰好在 k 分钟变空。 输出不仅仅是这是否可能：我们必须打印沙漏翻转时刻的确切序列。 

沙漏数量少是主要线索。 最多只有四个设备，每个设备的持续时间最多为二十分钟。 因此，单个沙漏可能出现的内部情况极少。 目标时间可以大到 1440，因此在目标时间之前模拟每种可能的策略需要小心。 尝试每个翻转序列的解决方案呈指数增长并且是不可能的，但基于状态的搜索可以适合，因为不同配置的数量是有限的。 

一个常见的错误是认为只有当前的剩余时间很重要，而不考虑过程中的确切时刻。 另一个错误是允许在任意时间翻转。 例如，使用输入```
1
5
3
```正确的输出是```
-1
```因为一个五分钟的沙漏只能完成五的倍数。 贪婪的方法在开始后立即翻转并假设它可以在三分钟后停止，这是违反规则的。 

另一个边缘情况是最后时刻。 用于输入```
2
3 5
5
```答案是存在的。 我们可以在零时间翻转两者，然后等到五分钟玻璃杯空。 最终输出必须包含时间为 5 且沙漏翻转为零的行。 当发现在转换期间已达到目标时间并且忘记所需的输出描述了该确切时刻的事件时，粗心的实现可能会停止。 

第三个微妙的情况是翻转一个已经空了的沙漏。 用于输入```
2
3 5
7
```即使五分钟玻璃仍在运行，三分钟玻璃也可以在时间三再次翻转。 当事件发生时，搜索必须允许沙漏的任何子集被翻转，包括刚刚变空的眼镜。 

# 方法

 直接暴力的想法是模拟每一个可能的翻转序列。 在每个事件时刻，最多有 4 个沙漏，因此最多有 16 个可能的子集可供翻转。 模拟将递归地尝试每个子集并继续，直到达到目标时间或证明分支失败。 

这种方法是正确的，因为每个合法测量实际上都是合法选择的序列，并且递归探索了所有这些。 问题在于重复状态的数量。 不同的序列可以产生相同的沙漏配置，但强力法会分别探索它们。 可能路径的数量随着事件的数量呈指数增长，即使每个单独的转换很小，也会使其变得太慢。 

关键的观察是，未来仅取决于当前时间和每个沙漏的当前状态。 我们如何达到这种情况的历史并不重要。 这使我们能够将相同的情况与广度优先搜索合并。 

状态存储当前分钟，以及对于每个沙漏，直到其当前运行侧变空为止剩余的时间量。 如果两个不同的序列达到相同的状态，则只需要保留一个，因为两者具有完全相同的可能的延续。 

可能的状态并不多。 当前时间只有 1441 个可能的值，每个沙漏只能有少量的剩余时间值。 由于有四个沙漏，持续时间长达二十个，这个状态空间对于 BFS 来说足够小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 事件数量呈指数增长 | 指数| 太慢了 |
 | 最佳| O(k * 乘积(ti + 1) * 2^n) | O(k * 乘积(ti + 1)) | 已接受 |

 # 算法演练

 1. 在时间零处从空配置启动 BFS。 初始状态表示任何沙漏开始之前的时刻。 保持此状态允许第一个操作在时间零发生，就像所有其他操作一样。 
2. 对于每个访问过的状态，尝试当前时刻可以翻转的沙漏的每个子集。 因为最多有 4 个沙漏，所以最多有 16 个子集。 
3. 应用所选的翻转。 如果沙漏是空的，则翻转它即可开始沙漏，并保持其剩余的完整持续时间。 如果它在当前方向上运行还剩 x 分钟，则翻转它会将剩余时间更改为 t - x，因为另一侧包含已经落下的沙子。 
4. 通过取最小的正剩余时间来找到下一个事件时刻。 这是下一次至少有一个沙漏变空的情况。 
5. 将时间向前移动该量，并将每个正剩余时间减少相同的量。 任何到达零的沙漏都会变空。 
6. 如果新状态未被访问过，则将其插入到 BFS 中。 存储先前的状态和翻转的子集，以便可以重建完整的序列。 
7. 当达到时间为 k 的状态时，重建路径。 最后打印的事件是没有翻转的目标时刻，因为当沙漏变空时测量结束。 

为什么它有效：

 BFS 的不变性是每个存储的状态在允许的事件时刻之后都是合法的情况。 每个转换都只应用一组合法的翻转，然后在某个沙漏清空时前进到下一个时刻，因此每个生成的状态也是合法的。 由于 BFS 探索每个可达状态并且从不丢弃唯一配置，因此到达时间 k 意味着存在有效序列。 如果 BFS 在未到达时间 k 的情况下完成，则每个可能的合法序列都已由已探索的某种状态表示，因此不存在解决方案。 

# Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n = int(input())
    t = list(map(int, input().split()))
    k = int(input())

    start = (0, (0,) * n)
    queue = deque([start])

    parent = {start: None}
    action = {}

    answer = None

    while queue:
        time, rem = queue.popleft()

        if time == k:
            answer = (time, rem)
            break

        for mask in range(1 << n):
            new_rem = list(rem)

            for i in range(n):
                if mask & (1 << i):
                    if new_rem[i] == 0:
                        new_rem[i] = t[i]
                    else:
                        new_rem[i] = t[i] - new_rem[i]

            if all(x == 0 for x in new_rem):
                continue

            delta = min(x for x in new_rem if x > 0)
            new_time = time + delta

            if new_time > k:
                continue

            for i in range(n):
                if new_rem[i] > 0:
                    new_rem[i] -= delta

            state = (new_time, tuple(new_rem))

            if state not in parent:
                parent[state] = (time, rem)
                action[state] = mask
                queue.append(state)

    if answer is None:
        print(-1)
        return

    path = []
    cur = answer

    while parent[cur] is not None:
        path.append((cur, action[cur]))
        cur = parent[cur]

    path.reverse()

    print(len(path) + 1)
    print(0, 0)

    for state, mask in path:
        time = state[0]
        flipped = [str(i + 1) for i in range(n) if mask & (1 << i)]
        print(time, len(flipped), *flipped)

if __name__ == "__main__":
    solve()
```BFS 队列仅包含合法事件之后立即发生的状态。 这`rem`元组存储剩余时间，直到每个沙漏清空。 值为零表示沙漏当前为空，可以通过翻转沙漏重新启动。 

转换逻辑是解决方案的核心。 当翻转一个玻璃杯时，剩余的时间就变成了对面的沙子数量。 对于长度为 t 的沙漏，还剩 x 分钟，该量为 t - x。 应用所有翻转后，模拟将直接跳转到下一个事件，而不是一分钟一分钟地前进。 

父词典仅用于重建。 它记录如何达到每个状态，这避免了在每个 BFS 节点内存储完整路径。 这使得内存使用量保持在较低水平。 

最终的重建打印初始时刻，然后打印用于达到 k 的每个事件。 最后一次转换到达时间 k，因为 BFS 仅在沙漏清空后才创建状态，因此目标时刻自动成为有效的结束事件。

 | 时间 | 活动结束后剩余 | 翻转 |
 | ---| ---| ---|

 | 5 | 1, 0 | 3 分钟玻璃 |
 | 7 | 0, 0 | 无 |

 搜索到达时间七，因为每次转换都恰好落在清空时刻。 最终状态确认测量结束而无需执行不必要的翻转。

# 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(k * 乘积(ti + 1) * 2^n) | 每个状态都会尝试所有可能的翻转子集。 |
 | 空间| O(k * 乘积(ti + 1)) | 每个可达时间和沙漏配置都存储一次。 |

 沙漏的最大数量只有四个，每个持续时间最多二十个，因此可能的内部配置数量很少。 1440 分钟的目标时间也足够小，足以使 BFS 状态空间保持在内存限制内。

 # 边缘情况

 对于持续时间为 5、目标为 3 的单杯：```
1
5
3
```BFS 以空状态开始。 翻转玻璃到达时间五，已经超出目标，因此不会生成时间三的状态。 算法正确打印`-1`。 

对于最终的活动要求：```
2
3 5
5
```BFS 在五分钟玻璃杯空后的时间五处达到状态。 重建打印初始翻转和零翻转的最终事件。 该算法不会将达到目标时间与需要另一次操作混淆。 

翻转空眼镜：```
2
3 5
7
```当三分钟玻璃杯在时间三空时，其剩余时间为零。 转换代码允许其再次翻转并在可用的三分钟内重新启动。 这正是创建七分钟测量所需的操作。
