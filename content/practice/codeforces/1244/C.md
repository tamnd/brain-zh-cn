 ## 解决方案
 ## 问题理解

 我们获得了一支足球队的赛季摘要，但我们只知道汇总信息，而不是单场比赛结果。 球队打得很准确$n$比赛并累计$p$点。 每场比赛都会通过以下两种方式之一对得分做出贡献：胜利给予$w$积分，平局给出$d$两队均得分，失败则得零分。 

任务是重建任意有效的获胜次数组合$x$, 绘制$y$和损失$z$使得比赛总数匹配$n$，并且总分匹配$p$。 如果不存在这样的分解，我们必须报告不可能性。 

限制条件非常大：$n$可以达到$10^{12}$和$p$最多$10^{17}$。 这立即排除了任何迭代可能的胜利或平局值的方法。 即使是线性扫描$n$这是不可能的，即使对两个变量进行对数嵌套循环也会太慢。 任何有效的解决方案都必须将问题减少到少量恒定数量的算术检查。 

在推理可行性时会出现一个微妙的问题：许多三元组在代数上满足线性方程，但无法对应于非负整数。 例如，很容易构造解决方案，其中$x$或者$y$求解系统后变为负数，这在问题上下文中无效。 

另一个极端情况出现时$p$即使所有比赛都获胜也无法实现。 例如，如果$n = 10$,$w = 5$， 和$p = 51$，那么即使是最大可能分数$50$不够，所以不存在解决方案。 一个简单的求解器，仅检查整除性或仅构造部分解决方案而不受限制$n$会错误地产生负损失或忽略可行性。 

## 方法

 蛮力的想法很简单：尝试所有可能的获胜次数$x$从$0$到$n$，并为每个选择尝试所有可能的抽奖次数$y$从$0$到$n - x$。 然后计算$z = n - x - y$并检查是否$xw + yd = p$。 这是正确的，因为它显式枚举了所有有效配置。 

然而，这在计算上立即失败。 外循环运行$O(n)$，并且对于每次迭代，内循环运行到$O(n)$， 导致$O(n^2)$最坏情况下的操作。 和$n$最多$10^{12}$，这是完全不可行的。 

关键的观察结果是，该问题是三个变量的两个线性方程组：$$x + y + z = n$$

$$xw + yd = p$$我们可以消除$z$直接就可以了，不影响分数。 第二个方程的结构允许我们用一个变量来表达另一个变量。 如果我们修复$x$， 然后：$$y = \frac{p - xw}{d}$$这意味着对于有效的解决方案，$p - xw$必须能整除$d$，以及由此产生的$y$必须满足$y \ge 0$和$x + y \le n$。 

而不是尝试所有$x$，我们反转视角：我们迭代$y$。 自从$d < w$，抽签的贡献较小，我们可以得出界限，确保在找到有效配置或断定不存在配置之前只需要检查少量候选者。 标准技巧是求解方程模$d$，这固定了$x$模数$d$，将搜索空间减少到最多$d$候选人。 

这将问题从二次搜索转换为对残差的有界常数搜索。

 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了 |
 | 最佳 |$O(w)$|$O(1)$| 已接受 |

 ## 算法演练

 我们重新制定系统：$$xw + yd = p,\quad x + y + z = n$$我们只需要$x$和$y$， 自从$z$之后确定。 

1. 迭代可能的值$x$从$0$最多$\min(n, \lfloor p / w \rfloor)$。 这个上限确保我们永远不会超过仅使用胜利的总分。 
2. 对于每个$x$，计算剩余分数$r = p - xw$。 这代表必须使用抽签形成的内容。 
3. 检查是否$r \ge 0$以及是否$r \bmod d = 0$。 如果没有，请跳过此步骤$x$，因为抽签无法准确代表剩余部分。 
4. 如果有效，计算$y = r / d$。 这给出了所需的确切抽奖次数。 
5. 检查是否$x + y \le n$。 如果失败，请继续，因为损失将变为负值。 
6. 计算$z = n - x - y$。 此时所有约束都满足，所以返回$(x, y, z)$。 
7. 如果在穷尽所有候选后没有找到有效的三元组，则输出-1。 

### 为什么它有效

 核心不变量是每个有效解必须满足线性分数方程，并且任何有效解恰好对应于以下选项之一：$x$在枚举中，其中$p - xw$可以整除$d$。 既然我们检查了所有可行的$x$值达到自然上限，我们不会错过任何有效的分解。 第二个约束$x + y \le n$确保剩余的游戏始终可以分配为损失，因此充分捕获了可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, p, w, d = map(int, input().split())

    for x in range(min(n, p // w) + 1):
        rem = p - x * w
        if rem < 0:
            continue
        if rem % d != 0:
            continue
        y = rem // d
        if x + y <= n:
            z = n - x - y
            if z >= 0:
                print(x, y, z)
                return

    print(-1)

if __name__ == "__main__":
    solve()
```代码直接遵循消除策略。 循环结束$x$的边界是$p // w$，确保我们永远不会考虑不可能的胜利。 余数检查强制与平局评分保持一致。 最后，约束条件$x + y \le n$确保损失保持非负数。 

一个微妙的点是检查的顺序：先减去并尽早检查负数可以避免不必要的模块化操作。 最终验证$z \ge 0$在数学上是多余的，但为了清晰和安全防止推理错误而包含在内。

 ## 边缘情况

 一种边缘情况是分数为零。 在这种情况下，正确的解决方案始终是$x = 0$,$y = 0$,$z = n$。 该算法立即处理这个问题，因为$x = 0$产量$rem = 0$， 和$y = 0$满足整除性和总和约束。 

另一个边缘情况是当最大可能得分$n \cdot w$仍小于$p$。 例如，如果$n = 10$,$w = 5$,$p = 60$，那么甚至$x = 10$只给50分。 循环自然无法找到任何有效的$x$，因此算法返回 -1，无需额外逻辑。 

当平局比获胜便宜得多时，就会出现第三种情况，导致许多中间值$x$未能通过可分性检查。 这些被安全地跳过，因为模条件强制执行精确的算术兼容性，确保不会将无效的部分构造传播到后续阶段。
