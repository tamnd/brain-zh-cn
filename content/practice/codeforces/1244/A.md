 ## 解决方案
 ## 问题理解

 波利卡普明天有两类工作：写讲座和在实践课上画画。 讲课时他必须使用笔，每支笔在用完之前只能用于有限的讲课次数。 对于实际课程，他必须使用铅笔，并且每支铅笔在变得无法使用之前可以在固定数量的课程中重复使用。 

任务是选择要带多少支钢笔和铅笔，以便可以覆盖所有讲座和实践课程，同时将所有东西放入最多可容纳的铅笔盒中$k$总计项目。 如果无法既满足工作负载要求又保持在容量范围内，我们必须报告失败。 

每个测试用例给出了讲座的数量$a$, 实践课$b$, 笔容量$c$, 铅笔容量$d$和总存储限制$k$。 我们输出任何有效的对$(x, y)$在哪里$x$笔涵盖所有讲座，$y$铅笔涵盖所有实践课程，并且$x + y \le k$。 

关键的限制是钢笔和铅笔在使用上是独立的，但受到共享容量限制。 这种耦合使得问题变得非同小可。 

输入范围很小，所有值最多为 100，最多 100 个测试用例。 这会立即排除任何比每个测试用例恒定时间更重的事情。 甚至一个$O(k^2)$这种方法理论上很好，但没有必要。 

当其中一个需求强制使用大量项目而容量很小时，就会出现微妙的边缘情况。 例如，如果$a = 10, c = 1$，那么至少需要10支笔。 如果$k < 10$，即使铅笔无关，答案也是不可能的。 仅检查总体可行性而不考虑每种类型最小值的天真的方法在这里会失败。 

如果试图贪婪地减少总项目而不考虑灵活性，就会出现另一个问题。 由于任何有效的对都被接受，因此最小化是不必要的，并且可能导致过度思考或不正确的平衡策略。 

## 方法

 暴力方法会尝试所有可能数量的笔$x$从 0 到$k$，计算他们可以讲多少个讲座，然后检查是否存在相应数量的铅笔$y$既满足覆盖范围限制又满足容量限制。 对于每个$x$，计算可行性是常数时间，所以总复杂度是$O(k)$每个测试用例。 这在限制下已经可以工作，但比需要的更复杂。 

关键的观察结果是，所需的最小笔数是固定的：每支笔覆盖$c$讲座，所以我们至少需要$\lceil a / c \rceil$笔。 同样，我们至少需要$\lceil b / d \rceil$铅笔。 如果我们精确地计算出这些最低要求的数量，那么剩下的唯一问题就是它们是否适合铅笔盒。 如果不这样做，增加任一类型只会使容量情况变得更糟，因为增加项目在固定上限下无助于可行性。 

这将问题简化为直接可行性检查，然后输出所需的最低配置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(k)$每次测试|$O(1)$| 已接受但没有必要 |
 | 最佳 |$O(1)$每次测试|$O(1)$| 已接受 |

 ## 算法演练

 1. 计算所需的最少笔数：$x = \lceil a / c \rceil$。 这确保了所有讲座都被覆盖，因为每支笔最多支持$c$讲座。 
2. 计算所需的最少铅笔数量：$y = \lceil b / d \rceil$。 这确保了所有实践课程都被涵盖，因为每支铅笔最多支持$d$类。 
3. 检查是否$x + y \le k$。 这确保了铅笔盒约束得到满足。 
4. 如果条件不成立，则输出$-1$因为即使是最有效的选择也已经超出了容量，任何替代方案只会增加使用量。 
5.否则，输出$x$和$y$。 任何额外的项目都是不必要的，并且该问题允许任何有效的配置，因此这个最小的构造就足够了。 

### 为什么它有效

 该构造使用每种类型的尽可能少的项目，但仍能满足工作负载要求。 任何有效的解决方案都必须至少单独使用这么多的钢笔和铅笔，因为减少其中任何一个都无法覆盖所有任务。 因此，即使这个最小配置超出了容量，也无法通过重新安排来解决它。 如果适合，它自动是一个有效的解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, c, d, k = map(int, input().split())

    pens = (a + c - 1) // c
    pencils = (b + d - 1) // d

    if pens + pencils > k:
        print(-1)
    else:
        print(pens, pencils)
```该计算通过整数运算使用上限除法，避免浮点运算。 每个测试用例都是独立处理的。 唯一的决策点是可行性检查$k$，它直接反映了存储约束。

## 测试用例```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        a, b, c, d, k = map(int, input().split())
        pens = (a + c - 1) // c
        pencils = (b + d - 1) // d
        if pens + pencils > k:
            out.append("-1")
        else:
            out.append(f"{pens} {pencils}")
    return "\n".join(out)

 ## 边缘情况

 当$a$不能被整除$c$，需要进行天花板划分。 例如，$a = 5, c = 2$给出$x = 3$。 使用未经调整的整数除法会错误地得到 2，这无法涵盖所有​​讲座。 

当容量恰好等于所需项目时，解决方案必须接受它。 例如，如果$x + y = k$，它仍然有效，并且拒绝相等会错误地丢弃正确答案。 

当任一$a = 0$或者$b = 0$，公式仍然正确运行，按预期生成零钢笔或铅笔，因为该类别不需要任何项目。
