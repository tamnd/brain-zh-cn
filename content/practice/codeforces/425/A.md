 ## 解决方案
 ## 问题理解

 我们得到一个整数数组和有限的交换操作预算。 每次交换允许交换数组中的任意两个位置，并且我们最多可以执行`k`这样的交换。 

目标是使用不超过`k`交换以获得某个分数函数，`m(a)`，变得尽可能大。 此函数为数组位置分配不同的权重：数组中较早放置的元素比较晚放置的元素对最终值的贡献更大。 具体来说，元素的贡献取决于它位于右侧的距离，因此在数组的前面引入较大的值是有益的。 

输入尺寸很小：`n ≤ 200`和`k ≤ 10`。 这立即排除了所有排列的任何指数策略，因为`n!`太大了。 甚至`O(n^3)`解决方案虽然有限，但可以接受； 任何涉及枚举所有重新排序的事情都是不可行的。 

一个非常小的存在`k`是关键的结构性约束。 这表明我们不希望自由地排列阵列，而是从原始配置开始进行有限数量的有影响力的编辑。 

微妙的边缘情况来自重复值和负数。 例如，当所有元素均为负数时，如果交换将较小负数推入高权重位置，同时留下非常负数，则交换实际上可能会降低分数。 同样，如果阵列已经是最佳的，则使用交换是可选的，不应强制使用。 

## 方法

 得分函数仅取决于数组的最终顺序，而不取决于我们如何达到它。 由于掉期是任意两个指数之间的任意交换，因此每次掉期都可以被视为选择两个头寸并一次性交换其价值。 

一个蛮力的想法是模拟最多的所有可能的序列`k`互换。 在每一步中，我们都会尝试所有对`(i, j)`，应用交换，并继续递归。 这是正确的，因为它会在允许的操作次数内探索每个可到达的配置。 然而，分支因子是`O(n^2)`每一步，深度是`k`，大致导致`O(n^(2k))`州，即使对于`k = 3`。 

关键的观察是，我们永远不需要考虑不涉及我们正在决定的当前头寸的掉期。 我们可以从左到右构建答案，而不是在全局范围内探索任意交换序列。 在位置`i`，我们决定应该将哪个值放在那里，最多使用一次交换将其从稍后的位置取出。 固定位置后`i`，我们继续前进。 

这将问题变成了一个受控的贪婪结构，并且对选择进行了回溯。 在每个索引处，我们要么将元素保留原样，要么将其交换到某个较晚的位置，消耗一个交换预算单位。 因为`k ≤ 10`，探索所有这样的选择都是可行的。 

因此，递归是在三个状态上定义的：当前索引、剩余交换数量以及数组的当前配置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 全排列搜索 | O(n! ) | O(n) | 太慢了 |
 | 递归交换模拟| O(n^(2k)) | O(n^(2k)) | O(n) | 太慢了 |
 | 具有交换选择的受控 DFS | O(k·n^2·n) | O(k·n^2·n) | O(n) | 已接受 |

 ## 算法演练

 我们使用深度优先搜索来构建解决方案，探索所有有意义的交换决策。 

1.从索引开始`i = 0`与原始数组和`k`可用交换。 前面的前缀`i`被认为是固定的。 
2. 如果立即停止，则计算当前数组的分数。 这充当基线候选者。 
3. 如果没有剩余掉期或`i`到达终点，返回计算出的分数。 
4. 否则，考虑改善当前的状况。 对于索引`i`,尝试交换`a[i]`每个位置`j ≥ i + 1`。 每次这样的交换都会消耗一次操作并生成一个新的数组配置。 
5. 执行交换后`(i, j)`，从索引开始递归求解子问题`i + 1`可用交换数量减少了 1 个。 这反映了这一立场`i`现在已经解决了，我们继续前进。 
6. 还可以考虑完全不交换位置`i`，然后直接进入`i + 1`具有相同的数组和相同的剩余交换。 
7. 在所有这些选择中取最大结果。 

我们总是从左到右进行的原因是，一旦位置固定，稍后更改它只会浪费掉期，而不会以受控的方式改善结构。 

### 为什么它有效

 在每个位置`i`，算法枚举在剩余交换预算下可以占据该位置的所有可能值。 至多任何有效序列`k`掉期会导致指数出现一些价值`i`在这些交换之后。 我们的过渡考虑了将任何候选人价值落实到位的所有方法`i`一次交换，然后递归地处理剩余的后缀，少一次交换。 这与任何有效交换序列的结构相匹配，因为每次交换要么影响当前位置，要么可以在不改变可行性的情况下延迟。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def compute_score(arr):
    n = len(arr)
    total = 0
    weight = n
    for x in arr:
        total += x * weight
        weight -= 1
    return total

def dfs(i, k, arr):
    n = len(arr)

    best = compute_score(arr)

    if i == n or k == 0:
        return best

    # option 1: do nothing at position i
    best = max(best, dfs(i + 1, k, arr))

    # option 2: try swapping i with any j > i
    for j in range(i + 1, n):
        arr[i], arr[j] = arr[j], arr[i]
        best = max(best, dfs(i + 1, k - 1, arr))
        arr[i], arr[j] = arr[j], arr[i]

    return best

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    print(dfs(0, k, a))

if __name__ == "__main__":
    main()
```该实现依赖于立即回溯的就地交换。 这避免了在每一步复制数组，否则会增加一个额外的因子`n`到复杂性。 

仅在需要时才重新计算分数函数。 自从`n ≤ 200`，重新计算它是可以接受的并且保持递归逻辑干净。 

一个微妙的细节是，我们总是在探索交换分支后恢复数组。 忘记这个恢复会破坏后面的分支并默默地产生不正确的结果。

 ## 边缘情况

 一种重要的边缘情况是数组只有一个元素。 该算法立即计算分数并返回，而无需输入递归，因为不可能进行交换或重新排序。 用于输入`1 5`带数组`[7]`，函数计算`7 * 1 = 7`并正确停止。 

另一种情况是所有元素都相等。 任何交换都会产生相同的配置。 DFS 仍然探索交换分支，但所有状态的分数保持不变。 为了`5 2`和`[3, 3, 3, 3, 3]`，每条递归路径都会产生相同的加权和，因此最大值保持稳定在`45`。
