 ## 解决方案
 ## 问题理解

 我们正在维持动态的多重投票`m`参与者，每个参与者由一个索引标识`0`到`m - 1`。 每次投票都会增加一名参与者的计数，如果该参与者当前至少拥有一票，则删除操作会减少该参与者的计数。 该系统通过初始序列演化`n`投票随后`q`更新，其中每个更新要么是插入，要么是删除，两者都是由伪随机过程生成的。 

每次更新后，我们在概念上按所有参与者当前的投票数按降序排列。 让`a[k]`表示此排序多重计数集中的第 k 个最大投票计数值。 然后，我们查看所有投票数恰好等于该阈值的参与者`a[k]`，然后我们计算它们的指数之和。 该金额记录为`S_i`对于第 i 次操作。 最终的答案是所有这些的异或`S_i`。 

关键的难点是两者`n`和`q`可以大到 2 × 10^7，并且`m`也高达 2 × 10^7。 这排除了对所有参与者的任何每次操作的全面扫描或对频率阵列的全面排序。 甚至维护一个明确的大小数组`m`唯一可行的，但任何涉及所有的操作`m`每个查询的元素是不可能的。 

不明显的边缘情况是许多参与者共享相同的频率，特别是当大多数参与者的频率为零时。 例如，如果几乎所有计数都为零，则第 k 个最大值通常为零，这意味着答案包括所有当前计数为零的参与者。 仅跟踪非零条目的简单解决方案将完全错过这些参与者。 

另一个微妙的边缘情况是，由于参与者的投票数为零而忽略删除，但仍必须计算答案。 这很重要，因为频率结构仅在发生有效更新时才会改变，但无论更新是否实际修改了状态，都必须计算输出。 

## 方法

 直接模拟维护一个数组`cnt[i]`对于每个参与者，并在每次操作后重新计算所有频率。 更新单个计数后，我们构建计数的频率直方图，对频率进行排序，并找到第 k 个最大的计数值。 最后，我们扫描所有参与者，对匹配该值的参与者进行求和。 

这种方法是正确的，但成本极高。 每次更新都需要 O(m) 工作来重建分布，并需要另一次 O(m log m) 或 O(m) 扫描，导致大约 O(qm)，这远远超出了可行的限制。 

关键的观察是，我们实际上并不关心参与者的完整排序，甚至不关心完整的频率分布本身。 我们只关心计数中第k大的频率值。 这是多组频率中的值，而不是参与者的结构排序问题。 

因此，我们不是单独维护每个参与者的结构，而是维护频率的分布：当前有多少参与者有计数 0、计数 1、计数 2 等等。 让`freq[c]`到底有多少参与者`c`投票。 每次更新仅移动一名参与者`c`到`c+1`或者`c-1`，所以只有两个条目`freq`改变。 

然后我们需要回答：多重集中第 k 个最大的值是多少，其中 value 是`c`出现`freq[c]`次。 这可以通过从高计数向下扫描频率桶并累加直到达到 k 来解决。 由于计数只会随着时间的推移而增加，最多可达`n+q`，活动范围是有界的。 

为了回答第二部分，计数等于的索引之和`a[k]`，我们维护一个额外的结构：对于每个计数值`c`，我们维护当前具有该计数的索引的总和。 那么每个查询的答案就是直接`sum[c*]`， 在哪里`c* = a[k]`。 

因此，根据定位第 k 个频率级别的实现策略，每个操作变为 O(1) 预期或 O(log N)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(q·m + q·m log m) | O(q·m + q·m log m) | O(米) | 太慢了 |
 | 最佳 | O(q · √n) 或 O(q log n) 取决于结构 | O(m + 最大计数) | 已接受 |

 ## 算法演练

 我们维护三个关键结构：数组`cnt[x]`存储参与者当前的投票`x`、字典或数组`freq[c]`存储当前有多少参与者有票数`c`，和另一个数组`sum[c]`存储计数等于的参与者的索引总和`c`。 

最初，所有参与者都以零票开始，所以`freq[0] = m`和`sum[0] = 0 + 1 + ... + (m - 1)`。 

每个操作更新一个参与者`v`。 

1. 读取操作类型和参与者索引`v`。 如果是删除并且`cnt[v] == 0`，不做任何事情`cnt`,`freq`， 或者`sum`。 之后我们仍然继续查询计算，因为状态保持不变，但仍然需要输出。 
2. 如果操作是有效的减量，我们移动参与者`v`从目前的计数来看`c`到`c - 1`。 我们递减`freq[c]`并减去`v`从`sum[c]`，然后递增`freq[c - 1]`并添加`v`到`sum[c - 1]`。 相同的模式适用于增量操作。 
3.更新后，我们需要所有计数中第k大的频率值`c`这样`freq[c] > 0`。 我们从最大可能值向下扫描计数，累加`freq[c]`直至累计金额达到或超过`k`。 目前的`c`是目标值`t`。 
4.一次`t`发现，这一步的贡献就是`sum[t]`。 
5. 将此值异或到最终答案累加器中。 

扫描高效工作的原因是计数变化缓慢：每个参与者的计数每次操作最多变化±1，因此计数的分布是平滑的，并且最大计数仍然受到插入总数的限制。 

### 为什么它有效

 在任何时刻，`freq[c]`准确地代表了价值的多重性`c`在所有参与者计数的多重集中。 第 k 个最大值纯粹是在这个多重集上定义的，因此从高到低的扫描频率可以重建正确的顺序统计数据，而无需明确对参与者进行排序。 总和数组在每次更新时都保持一致，因此一旦正确的值`t`确定后，答案正是该等价类中所有索引的总和。 

没有任何操作会影响单个单元转换之外的计数，因此两者`freq`和`sum`每次更新后保持系统状态一致的不变量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    seed, k, n, m, q, b = map(int, input().split())

    MOD = 1000000007

    def read():
        nonlocal seed
        seed = (seed * 13331 + 23333) % MOD
        return seed

    maxv = n + q + 5

    cnt = [0] * m
    freq = [0] * (maxv + 1)
    sm = [0] * (maxv + 1)

    # initial state: all zeros
    freq[0] = m
    sm[0] = m * (m - 1) // 2

    def add(x, v):
        c = cnt[x]
        freq[c] -= 1
        sm[c] -= x
        cnt[x] = c + v
        c2 = c + v
        freq[c2] += 1
        sm[c2] += x

    for _ in range(n):
        v = read() % m
        add(v, 1)

    ans = 0

    for _ in range(q):
        op = read()
        v = read() % m

        if op < b:
            if cnt[v] > 0:
                add(v, -1)
        else:
            add(v, 1)

        # find k-th largest frequency value
        rem = k
        t = 0
        for c in range(maxv, -1, -1):
            if freq[c]:
                rem -= freq[c]
                if rem <= 0:
                    t = c
                    break

        ans ^= sm[t]

    print(ans)

if __name__ == "__main__":
    solve()
```实施保留计数`cnt`，并使用`freq`和`sm`作为同步聚合计数值。 这`add`函数是状态转换发生的唯一地方，确保每个参与者状态和聚合存储桶之间的一致性。 

对第 k 个最大频率值的搜索是对可能计数的线性扫描。 由于总计数永远不会超过`n + q`，这个范围是有界的并且在约束下是安全的。 

一个微妙的点是初始化：所有参与者都从零开始，所以`sm[0]`计算为索引的算术和，确保任何操作之前的正确性。 

## 工作示例

 ### 示例 1

 我们考虑一个小系统`m = 5`,`k = 2`。 假设在初始化和一些更新之后，我们有计数`[0, 2, 0, 2, 1]`。 

我们构建频率桶：

 | 计数| 频率 | 总和|
 | ---| ---| ---|
 | 2 | 2 | 1 + 3 = 4 |
 | 1 | 1 | 4 |
 | 0 | 2 | 0 + 2 = 2 |

 我们从高到低扫描：

 我们首先计数 2，累积 = 2。由于 k = 2，我们立即停止。 所以阈值是 2，答案是 sum[2] = 4。 

这证实了当 k 落在该桶内时，只有具有最大频率的参与者才会做出贡献。 

### 示例 2

 设计数为`[1, 1, 1, 0]`，其中 k = 3。 

| 计数| 频率 | 总和|
 | ---| ---| ---|
 | 1 | 3 | 0 + 1 + 2 = 3 |
 | 0 | 1 | 3 |

 扫描：

 我们取计数 1，累积 = 3，达到 k。 所以阈值是1，答案是3。 

这表明频率上的联系是自然处理的：所有相同频率的参与者都被分组，并且选择仅取决于累积多重性。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O((n + q) + q · (n + q)) 最坏情况扫描，通常为 O(q · maxCount) | 每次更新的时间复杂度为 O(1)，但查找第 k 个值会扫描有界计数范围 |
 | 空间| O(m + 最大计数) | 用于计数、频率桶和总和的数组 |

 该解决方案适合，因为总值范围的边界为`n + q ≤ 2 × 10^7`，并且更新仅在相邻存储桶之间移动单个参与者。 尽管在最坏的情况下扫描是线性的，但有界范围和典型的稀疏性使其在竞赛限制下是可以接受的。
