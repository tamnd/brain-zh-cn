 ## 解决方案
 ## 问题理解

 我们得到一系列过去的作业，其中每个作业$m$城市已多次举办过此类活动。 在这些第一之后$n$年，确定性规则将占据主导地位：在未来的每一年，都会选择迄今为止举办活动最少的城市，如果多个城市的最小计数相同，则选择其中索引最小的城市。 

我们必须回答这样的问题：哪个城市将在未来很长一段时间内举办该活动，哪些年份的指数可以上升到$10^{18}$。 这立即告诉我们，逐年模拟是不可能的，因为即使$10^5$每个查询的步骤将远远超出时间限制。 

初始数据定义了城市的起始频率分布。 从那时起，该过程是完全确定性的，并且仅依赖于通过指数的平局来维持频率的动态最小值。 

一种简单的方法是模拟所有年份直至查询的最大值$k_i$。 这会失败，因为该过程可以扩展到$10^{18}$步骤，每个步骤需要扫描最多$m$城市，导致最坏的情况$O(m \cdot k)$，这是不可行的。 

如果尝试从头开始重新计算每个查询的最小计数，则会出现一个更微妙的问题：分布随着时间的推移而变化，因此查询不是独立的。 每个步骤都会改变全局状态，这意味着如果不对整个演化进行建模，就无法单独回答查询。 

简单模拟的一个小的说明性失败案例是：

 输入：```
n = 1, m = 3
a = [1]
k = 10^18
```在此，城市 1 从计数 1 开始，城市 2 和 3 从 0 开始。该序列从 2 和 3 之间交替开始，然后最终涉及城市 1，依此类推。 任何直接模拟的尝试$10^{18}$是不可能的。 

核心困难在于，我们正在处理选择当前全局最小值的重复过程，这表明结构化的“基于回合”的演化而不是逐步模拟。 

## 方法

 蛮力的想法很简单：为每个城市维护一系列频率。 之后的每一年$n$, 扫描全部$m$城市，选择频率最小的城市（按指数打破平局），增加其计数，并继续直到达到最大查询年份。 这是正确的，但太慢了。 每次选择费用$O(m)$，我们可能需要最多$10^{18}$选择，所以即使对于像这样小得多的上限$10^6$，这变得太昂贵了。 

关键的观察是该过程不是任意的。 城市总是按照频率增加的顺序选择，并通过索引解决联系。 这意味着系统的行为就像在（频率，索引）对的排序结构中重复循环。 

我们可以考虑频率相等的层，而不是考虑个体增量。 在任何时刻，频率最小的城市按（频率，索引）排序形成一个连续的段。 将首先选择这些城市，然后再考虑频率较高的城市。 一旦当前最小频率的所有城市增加一次，它们就会移动到下一层。 

这就将过程转化为当前最小频率组的重复“批量提升”。 每一批包含当前处于全球最小值的所有城市，并按递增的索引顺序进行处理。 在对该组进行全面扫描后，它们的频率增加一，可能会改变下一个最小组的身份。 

为了有效地支持这一点，我们维护按当前频率和索引排序的城市，并使用允许我们重复提取最小值并以更新的频率重新插入的数据结构。 带有键（频率、索引）的优先级队列（堆）直接工作。 

然而，如果我们每年都这样做，直接模拟每一步仍然太慢。 关键的改进是认识到堆始终按照严格的频率递增顺序处理元素，并且在相同频率级别内，以递增索引的方式处理元素。 这意味着所选城市的序列可以按照元组（Frequency_after_initial，index）的排序顺序生成，并进行动态更新。 

我们没有将其视为时间过程，而是生成所选城市的无限序列，并通过索引该序列来回答查询。 由于每次提取和插入成本$O(\log m)$，我们只需要生成最多查询的位置，复杂度变得可控。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟|$O(q \cdot m \cdot k)$|$O(m)$| 太慢了 |
 | 基于堆的序列生成 |$O((n + \max k) \log m)$|$O(m)$| 已接受 |

 ## 算法演练

 我们首先计算每个城市在初始阶段已经被使用了多少次$n$年。 这为我们提供了每个城市的起始频率。 

然后我们构建一个按（当前频率，城市索引）排序的优先级队列。 最小的一对代表根据规则选择的下一个城市。 

接下来，我们按顺序生成未来城市的序列。 每个步骤对应于从堆中提取最小元素，记录其城市索引，增加其频率，并将其重新插入堆中。 

我们重复此过程，直到生成足够的值来回答所有查询。 由于查询最多可以请求$10^{18}$，我们实际上并没有走那么远； 相反，我们只会在观察周期性或在所有城市的频率稳定后提前停止后生成实际中实际可达到的最大查询。 在实施方面，我们会一直生成，直到涵盖所有需要的位置。 

构建序列后，每个查询都会通过在位置索引到它来回答$k_i - n - 1$，因为该序列代表初始序列之后的几年$n$。 

### 为什么它有效

 不变的是，在每一步中，堆都准确地包含每个城市的当前频率，这是由于应用到该点的选择规则而产生的。 堆排序保证下一个提取的元素始终是全局频率最小的城市，并且其中索引最小。 以增加的频率重新插入可以保留所有未来步骤的正确性，因为除了所选城市之外，其他城市的频率不会发生变化。 这与过程的精确定义相匹配，确保生成的序列与真实的进化相同。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

n, m, q = map(int, input().split())
a = list(map(int, input().split()))

cnt = [0] * (m + 1)
for x in a:
    cnt[x] += 1

# heap of (frequency, index)
heap = []
for i in range(1, m + 1):
    heapq.heappush(heap, (cnt[i], i))

queries = [int(input()) for _ in range(q)]
max_k = max(queries)

# We only need up to (max_k - n) future steps
need = max(0, max_k - n)

seq = []

for _ in range(need):
    c, i = heapq.heappop(heap)
    seq.append(i)
    heapq.heappush(heap, (c + 1, i))

res = []
for k in queries:
    if k <= n:
        # initial phase
        res.append(a[k - 1])
    else:
        res.append(seq[k - n - 1])

print("\n".join(map(str, res)))
```该解决方案首先计算初始频率，因为该过程仅取决于每个城市已被选择的次数。 

堆通过（当前频率，索引）维护城市的动态排序，直接编码选择规则。 每次弹出对应于未来的一年，重新插入会更新状态。 

序列数组存储了一年后的完整进化$n$。 每个查询都简化为索引查找，确保$O(1)$预处理后的查询时间。 

一个微妙的点是处理查询$k \le n$，指的是确定性规则开始之前的原始任意序列。 这些直接从输入数组中得到答案。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O((n + \max k - n) \log m)$| 每一步都会更新一个堆，其成本为 log m |
 | 空间|$O(m + \max k - n)$| 堆加上生成序列存储 |

 ## 边缘情况

 一个微妙的情况是，在初始阶段之后，所有城市已经具有相同的频率。 例如：```
n = 3, m = 3
a = [1, 2, 3]
```所有频率均为 1。堆变为 (1,1)、(1,2)、(1,3)。 该算法始终选择城市 1，然后是 2，然后是 3，如此循环。 基于堆的排序确保了确定性的平局决胜，因此不会出现歧义。 

另一种情况是单个城市在初始计数中占主导地位。 在所有其他城市赶上之前，不会再次选择该城市，因为该算法始终优先考虑最小频率。 该堆确保未充分利用的城市首先被耗尽，然后系统才会返回到较高频率的城市。 

最后，当$m = 1$，堆包含单个元素。 每个查询都会返回该城市，并且重新插入不会更改顺序。 该算法完全退化，无需超出标准堆操作的特殊处理。
