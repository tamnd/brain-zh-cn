 ## 解决方案
 ## 问题理解

 两个人持有一定数量的货币，并且可以选择在消费之前在彼此之间转移整数金额。 每个货币单位可以购买一件大块的物品`z`，这意味着每个人独立地将他们的钱转换成`floor(money / z)`项目。 目标是在两个人之间重新分配总资金，以使这些楼层分配的总和最大化。 在找到最佳的重新分配方案后，我们还需要最大限度地减少它们之间转移的资金，同时仍然达到最大的物品数量。 

关键对象是函数`f(t) = floor(t / z)`。 总分是`f(x') + f(y')`在哪里`x' + y' = x + y`。 转账保留了总金额，因此问题就变成了如何将固定金额分成两部分以使楼层总和最大化。 

约束条件达到`10^18`，这会立即排除任何尝试所有可能的重新分配的解决方案。 即使迭代可能的转移金额也需要最多`10^18`在最坏的情况下采取步骤，这是不可行的。 这迫使解决方案基于除法的算术特性而不是模拟。 

当两者都出现时，就会出现微妙的边缘情况`x`和`y`已经是的倍数`z`。 在这种情况下，任何转移都无法改善结果，任何转移都只会带来总数下降的风险。 另一个重要的情况是，当一个人的资产略低于`z`，因为转移少量硬币可以将它们推过边界，并使它们的贡献增加 1。 

例如，如果`z = 5`,`x = 4`,`y = 1`，那么在没有转移的情况下，两者都有贡献`0`。 但是移动 1 个硬币就会`(5, 0)`，将总数增加到`1`。 这表明只有跨界转移才重要。 

## 方法

 蛮力的想法是尝试所有可能的移动方式`k`硬币从一个人到另一个人，其中`k`范围从`-x`到`y`。 对于每个分割`(x + k, y - k)`, 计算`floor((x + k)/z) + floor((y - k)/z)`并追踪最佳结果。 这是正确的，因为它枚举了所有有效的重新分配。 然而，范围`k`可以达到`10^18`，使得这完全不可行。 

关键的观察是`floor(t / z)`仅当发生变化时`t`跨越多个`z`。 这意味着唯一有用的转移是那些推动`x`或者`y`跨越最接近的倍数`z`。 超出倍数的任何额外转移要么没有任何作用，要么会降低对方的下限价值。 

因此，我们不是搜索所有分割，而是只检查恒定数量的候选：当前分割，以及将每个值向上或向下移动到最接近的倍数的调整`z`。 由于每个人的价值只与模数有关`z`，问题简化为关于余数的推理以及如何将它们交换为完整大小的块`z`。 

我们计算总和`S = x + y`。 最大可能的项目数始终是`S // z`，因为转账不能改变总金额。 唯一剩下的任务是确保这个界限是可以实现的，并确定达到双方与多个数最佳对齐的配置所需的最小传输量。`z`。 

最优策略是尝试使一侧尽可能接近`z`通过转移完成一个区块所需的最小数量的硬币。

 ## 算法演练

 1.计算总金额`S = x + y`。 这是固定的，因此任何重新分配都会保留它。 
2. 计算椰子的最大可能数量：`S // z`。 再分配不能超过这个，因为每个椰子的成本`z`总金额是不变的。 
3. 计算距离`x`来自下一个倍数`z`， IE。`x % z`，类似地对于`y % z`。 这些余数决定传输是否可以增加任一侧的完整块数。 
4. 检查两个余数是否为零。 如果是这样，任何转移都无法改善任何事情，因为两者都已经与块边界完美对齐。 
5. 否则，确定移动至少一侧穿过尺寸边界所需的最小转移量`z`。 这是通过将硬币从一侧移动到另一侧直到余数正好为零来实现的。 最小转移是以下较小者`x % z`（从 x 移动到 y）或`y % z`（从 y 移动到 x），取决于我们首先尝试完成哪一侧。 
6.输出最大椰子数和这个最小转移值。 

### 为什么它有效

 下取整函数仅在某个值跨越以下倍数时才会改变`z`。 任何不改变双方商数的转移都与目标无关。 因此，最优解必须位于至少一侧可被整除的边界处`z`。 在所有这些触及边界的举动中，最小化转移的硬币相当于最小化到最接近的倍数的距离。`z`两侧。 这将整个优化问题简化为局部余数调整。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

x, y, z = map(int, input().split())

s = x + y
max_coconuts = s // z

rx = x % z
ry = y % z

if rx == 0 and ry == 0:
    print(max_coconuts, 0)
else:
    # minimal transfer to make one side reach a multiple of z
    ans_move = min(rx, ry)
    print(max_coconuts, ans_move)
```第一部分严格根据再分配不会改变总货币这一不变量来计算椰子总数。 余数`rx`和`ry`捕捉每个人距离形成额外的完整椰子块还有多远。 最小转移对应于将较小的间隙固定为`z`。

import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    x, y, z = map(int, input().split())

    import io as _io

    with redirect_stdout(out):

    return out.getvalue().strip()

 ## 边缘情况

 当两个值都可以被整除时`z`，任何转移都不能增加完整组的数量，因为每个单元都已经完美包装。 用于输入`10 10 5`，两者都贡献了两个单位，任何转移只会减少一方的商，然后可能会增加另一方的商，使总数保持不变或更糟。 

当一侧非常接近倍数时，例如`1 8 3`，转移一个单位就足以跨越一侧的边界。 该算法捕获了这一点，因为最小余数直接测量每条边距边界的距离，而较小的余数代表触发商增加的最便宜的方式。
