 ## 解决方案
 ## 问题理解

 我们有一个矩形网格`n`行和`m`列，其中每个单元格已经具有三种颜色之一。 目标是重新绘制一些单元格，使最终网格看起来像由三个水平条纹组成的“旗帜”图案。 

每个条纹必须跨越网格的整个宽度。 顶部条纹具有一种统一颜色，中间条纹具有另一种统一颜色，底部条纹具有第三统一颜色。 颜色必须是三种可用颜色的排列，因此每种颜色仅使用一次，但它们的垂直顺序不是预先固定的。 

网格逐个单元重新绘制的成本很高，因此与初始配置相比，我们希望最大限度地减少改变颜色的单元数量。 

输出是将给定网格转换为任何有效的三条纹标志配置所需的重新绘制单元的最小数量。 

这些限制意味着简单的方法必须非常小心地处理复杂性。 对于多达几千行和几千列，任何尝试以简单的方式重新计算每个可能的分割的完整网格成本的解决方案都将失败，因为检查单个配置已经涉及所有`n × m`细胞，并且条纹边界的数量是二次方`n`。 这推动我们进行预计算和重用部分结果。 

一些边缘情况在实践中很重要。 如果所有单元格已经形成完美的单色网格，则答案不为零，除非该颜色可以一致地占据所有三个条纹，这是不可能的，因为条纹必须是不同的颜色。 另一个棘手的情况是当一种颜色在列或行中占据主导地位时； 每列天真的贪婪重绘可能会失败，因为最佳结构是整个网格的全局结构，而不是每列独立的结构。 

当最佳分割点“局部不明显”时，就会出现一种特别微妙的失败情况。 例如，即使行的上半部分看起来主要是一种颜色，如果同时减少许多列的重新绘制成本，则最佳边界可能会移动一行。 这正是强力计算变得昂贵但结构化前缀计算变得强大的地方。 

## 方法

 蛮力的想法很简单。 我们想尽办法将网格分成三个水平部分：选择两个切割点`i`和`j`，然后将三种颜色的排列分配给顶部、中间和底部部分。 对于每个这样的配置，我们计算有多少单元格已经匹配所需的颜色，并从总单元格中减去以获得重绘成本。 

这是有效的，因为它直接评估问题的定义。 然而，它太慢了，因为对于每对`(i, j)`对于每个排列，我们扫描所有`n × m`细胞。 这导致大约`O(n^3 * m)`如果天真地实施这种行为，那就远远超出了限制。 

关键的观察结果是，各列在成本累积方面是独立的。 对于固定行段和固定目标颜色，成本仅取决于该段中已经与颜色匹配的单元格数量。 这使我们能够聚合每行而不是每个完整矩形的信息。 

我们不是重新计算每个分割的不匹配计数，而是预先计算每行中有多少单元格已经具有每种颜色。 然后我们将行段转换为这些预先计算值的总和。 这将问题简化为选择两个分割点并评估每个配置的常量时间表达式。 

这将问题转化为在预处理后对每个案例进行恒定时间评估的行边界的二次扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²·n·m) | O(n²·n·m) | O(1) | O(1) | 太慢了 |
 | 前缀聚合| O(n² + n·m) | O(n² + n·m) | O(n·3) | 已接受 |

 ## 算法演练

 1. 对于每一行和每种颜色，计算该行中有多少个单元格已经具有该颜色。 这会将每一行压缩成一个小的摘要，而不是存储完整的列。 
2. 将这些计数转换为每种颜色行上的前缀和。 这使我们能够快速计算任何连续的行块中存在多少给定颜色的单元格。 
3. 枚举所有可能的分割点`i`和`j`这样`0 ≤ i < j < n`，代表三个水平条纹。 
4. 枚举三种颜色的所有排列，因为任何颜色都可以分配给任何条纹顺序。 
5. 对于每种配置，计算喷漆成本：

 - 顶部部分`[0..i]`必须变成A色
 - 中段`[i+1..j]`必须变成B色
 - 底部部分`[j+1..n-1]`必须变成C色

 每个分段成本是使用前缀和计算的：对于一个分段，我们知道有多少单元格已经与目标颜色匹配，因此重绘成本是分段中的总单元格减去匹配单元格。 
6. 在所有选择中保持最低成本。 

关键的想法是，每次评估都避免接触单个单元格，而是完全依赖于预先计算的行摘要。 

### 为什么它有效

 对于任何固定的行段和颜色，每个单元格都会独立地影响成本：它要么匹配目标颜色，要么不匹配。 由于行是独立的并且贡献线性增加，因此我们可以安全地将每一行压缩为每种颜色的计数，而不会丢失信息。 前缀和准确地保留了段查询，因此每个候选配置都可以正确评估，而无需再次检查网格。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    colors = ['R', 'G', 'B']

    cnt = [[0] * 3 for _ in range(n)]

    color_id = {'R': 0, 'G': 1, 'B': 2}

    for i in range(n):
        for j in range(m):
            cnt[i][color_id[grid[i][j]]] += 1

    pref = [[0] * 3 for _ in range(n)]
    for c in range(3):
        pref[0][c] = cnt[0][c]
        for i in range(1, n):
            pref[i][c] = pref[i - 1][c] + cnt[i][c]

    def get(col, l, r):
        if l > r:
            return 0
        res = pref[r][col]
        if l > 0:
            res -= pref[l - 1][col]
        return res

    import itertools

    total_cells = m * n
    ans = total_cells

    for i in range(n):
        for j in range(i + 1, n):
            for perm in itertools.permutations([0, 1, 2]):
                a, b, c = perm

                top = get(a, 0, i)
                mid = get(b, i + 1, j)
                bot = get(c, j + 1, n - 1)

                cost = total_cells - (top + mid + bot)
                if cost < ans:
                    ans = cost

    print(ans)

if __name__ == "__main__":
    solve()
```该实现首先将每一行压缩为三个计数，每种颜色一个。 这样就无需在评估过程中重新访问单个单元。 然后，前缀数组将按行计数转换为范围查询支持，以便可以在恒定时间内评估任何条带段。 

功能`get`是将行间隔转换为所选颜色的已正确单元格计数的关键抽象。 最终成本计算使用总单元格减去正确着色的单元格，这避免了重复的减法逻辑。 

三重嵌套循环`i`,`j`，并且排列是安全的，因为所有繁重的工作都已预先计算完毕。 

## 工作示例

 考虑一个小网格：```
RRG
GBB
RRG
```这里`n = 3`,`m = 3`。 

我们计算行数：

 | 行| 右 | G | 乙|
 | --- | --- | --- | --- |
 | 0 | 2 | 0 | 1 |
 | 1 | 1 | 1 | 1 |
 | 2 | 2 | 0 | 1 |

 前缀和：

 | 行| 右 | G | 乙|
 | --- | --- | --- | --- |
 | 0 | 2 | 0 | 1 |
 | 1 | 3 | 1 | 2 |
 | 2 | 5 | 1 | 3 |

 现在选择分割`i = 0`,`j = 1`，和排列`(R, G, B)`:

 | 段 | 行 | 颜色 | 匹配细胞|
 | --- | --- | --- | --- |
 | 顶部 | 0 | 右 | 2 |
 | 中| 1 | G | 1 |
 | 机器人 | 2 | 乙| 1 |

 匹配总数 = 4，单元格总数 = 9，成本 = 5。 

该跟踪显示了算法如何评估完整配置，而无需重复检查各个单元，完全依赖于前缀和。 

现在考虑另一个分裂`i = 1`,`j = 2`，相同的排列：

 | 段 | 行 | 颜色 | 匹配细胞|
 | --- | --- | --- | --- |
 | 顶部 | 0-1 | 右 | 3 |
 | 中| 2 | G | 0 |
 | 机器人 | 无 | 乙| 0 |

 总匹配数 = 3，成本 = 6。 

这演示了改变边界如何改变全局贡献，而不是局部每行。 

## 复杂度分析

 | 测量| 复杂性 | 说明|

 该解决方案完全符合限制，因为价格昂贵`n × m`网格扫描仅进行一次。 所有后续评估都简化为恒定时间算术，使得行分割上的二次枚举对于最多几千行的典型限制也是可行的。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    colors = ['R', 'G', 'B']
    color_id = {'R': 0, 'G': 1, 'B': 2}

    cnt = [[0] * 3 for _ in range(n)]
    for i in range(n):
        for j in range(m):
            cnt[i][color_id[grid[i][j]]] += 1

    pref = [[0] * 3 for _ in range(n)]
    for c in range(3):
        pref[0][c] = cnt[0][c]
        for i in range(1, n):
            pref[i][c] = pref[i - 1][c] + cnt[i][c]

    def get(col, l, r):
        if l > r:
            return 0
        res = pref[r][col]
        if l > 0:
            res -= pref[l - 1][col]
        return res

    import itertools
    total = n * m
    ans = total

    for i in range(n):
        for j in range(i + 1, n):
            for p in itertools.permutations([0, 1, 2]):
                a, b, c = p
                top = get(a, 0, i)
                mid = get(b, i + 1, j)
                bot = get(c, j + 1, n - 1)
                ans = min(ans, total - (top + mid + bot))

    return str(ans)

 ## 边缘情况

 所有行都相同的情况突出表明解决方案仍然必须强制使用三种不同的条纹颜色。 即使每个单元格都已经适合一种颜色，也只有一个条纹可以受益，因此其余条纹会产生重新绘制成本。 

另一种微妙的情况发生在`n = 3`。 这里只有一个有效的分割`(0,1)`，并且段边界中的任何差一错误都会立即破坏正确性。 前缀和逻辑确保每个段的计算都包含正确对齐的边界，因此不会重复计算或遗漏任何行。 

最后的边缘情况是最佳解决方案分配与自然输入分布不同的颜色顺序。 由于检查了所有六种排列，因此该算法不假设任何固定映射，从而防止对输入排序的隐藏偏差。
