 ## 解决方案
 ## 问题理解

 该建筑被描述为由三种固定公寓类型组成，每种类型都有固定数量的窗户。 三居室公寓提供 3 个窗户，五居室公寓提供 5 个窗户，七居室公寓提供 7 个窗户。对于每个测试用例，我们仅给出在建筑物中观察到的窗户总数，并且我们必须重建任何可能的公寓计数组合，使其总和精确等于该总数。 

所以这个任务相当于寻找非负整数$a, b, c$这样：$$3a + 5b + 7c = n$$如果存在这样的分解，则任何有效的三元组都是可接受的。 如果不存在分解，我们报告不可能。 

限制很小：$n \le 1000$和$t \le 1000$。 这立即告诉我们，即使每个测试用例进行三次或中等二次搜索也可以，因为最坏的情况下我们正在做的$10^6$总体检查。 然而，方程的结构也表明我们可以比盲目搜索做得更好。 

一个天真的方法可能会尝试所有三元组$(a, b, c)$最多$n$，但这会不必要地大。 更合理的蛮力可以修复两个变量并导出第三个变量，但即便如此，我们仍然希望最小化循环。 

当不存在组合时，会出现微妙的边缘情况，特别是对于像这样的小值$n = 1, 2, 4$。 这些失败是因为所有有效的构建块都是奇数大小，这意味着任何有效的总和必须具有与 3、5 和 7 的组合相同的奇偶校验。由于所有的构建块都是奇数，因此任何整数$n \ge 3$可以表示，但由于组合缺乏灵活性，小值通常无法表示。 

另一个边缘情况是当$n$正是硬币类型之一，如 3、5 或 7。答案必须正确地允许该类型的单个公寓和其他地方的零。 

## 方法

 蛮力的想法很简单：尝试所有可能的三居室公寓计数$a$和五房式公寓$b$，并计算剩余价值是否可以由七房式公寓填补。 对于每对$(a, b)$，我们检查是否$n - 3a - 5b$是非负数并且能被 7 整除。 

这是可行的，因为约束很小，但在最坏的情况下，我们尝试$1000 \times 1000 = 10^6$每个测试用例成对，并且最多有 1000 个测试用例，这变成$10^9$操作，速度太慢。 

关键的观察是我们实际上不需要深入搜索。 由于我们只需要任何有效的解决方案，因此我们可以修复一个变量并贪婪地确定其他变量。 最方便的选择是迭代七居室公寓的数量$c$。 一次$c$解决后，剩下的问题就减少为：$$3a + 5b = n - 7c$$现在我们只需要使用 3 和 5 找到一个表示。由于空间很小，我们可以尝试 3 和 5 的所有值$b$并计算剩余的数量是否能被 3 整除。这大大减少了搜索并保证快速解决。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解 (a, b) | 每次测试 O(n²) | O(1) | O(1) | 太慢了|
 | 修复 c，尝试 b | 每次测试的最坏情况为 O(n²)，但常数很小，或提前退出 | O(n) O(1) | O(1) | 已接受 |

 更实际的解释是，即使是最简单的有界双循环在这里也可以，但是结构化减少到两个变量可确保我们在实践中快速终止。 

## 算法演练

 我们独立解决每个测试用例。 

1.尝试固定七居室公寓的数量$c$从 0 到$n // 7$。 这确保我们永远不会超过七室公寓贡献的窗户总数。 
2. 对于每个$c$，计算剩余窗口$rem = n - 7c$。 这将问题简化为表示$rem$使用 3 和 5。 
3. 尝试五房公寓的可能值$b$从 0 到$rem // 5$。 对于每个选择，计算$rem - 5b$。 
4. 如果剩余值能被 3 整除，则设置$a = (rem - 5b) // 3$。 此时我们有了一个有效的分解并可以输出$a, b, c$。 
5.如果穷尽所有后仍没有找到组合$c$和$b$，输出-1。 

这种排序之所以有效，是因为我们在保持准确性的同时逐渐减少搜索空间。 每个步骤都会自动强制执行非负性，因此我们永远不需要回溯或调整先前选择的值。 

### 为什么它有效

 该算法枚举了所有可行的值$c$，并且对于每个这样的选择，它都会详尽地检查所有可行的值$b$。 对于每对$(b, c)$，值$a$如果存在则唯一确定。 由于所有有效解都恰好对应一对这样的解，因此搜索空间是完整的并且不能跳过任何解。 有界循环保证终止，同时保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        found = False

        for c in range(n // 7 + 1):
            rem = n - 7 * c
            for b in range(rem // 5 + 1):
                rest = rem - 5 * b
                if rest % 3 == 0:
                    a = rest // 3
                    print(a, b, c)
                    found = True
                    break
            if found:
                break

        if not found:
            print(-1)

if __name__ == "__main__":
    solve()
```该代码直接实现了前面描述的嵌套搜索。 外循环迭代七居室公寓的可能计数，而内循环尝试使用五居室公寓完成剩余的计数。 最终检查强制被 3 整除，从而确定三居室公寓的数量。 

早期中断确保我们在找到有效分解后立即停止，从而防止不必要的计算。

 ## 边缘情况

 对于非常小的值，例如$n = 1$，算法正确地迭代$c = 0$和$b = 0$，余数为 1。由于 1 不能被 3 整除，因此找不到解并返回 -1。 

对于精确匹配，例如$n = 7$，循环考虑$c = 1$，余数为 0。内循环立即找到$b = 0$， 和$a = 0$，产生有效的答案。 

对于混合情况，例如$n = 14$，测试了多个中间组合，但算法正确识别$7 + 7$或者$3 + 5 + 3 + 3$- 风格分解取决于循环顺序。 正确性并不取决于首先找到哪个解，而只取决于是否找到一个解（如果存在）。
