 ## 解决方案
 ## 问题理解

 我们从整数开始`1`通过`n`写在白板上。 在一次操作中，我们选择棋盘上当前的任意两个数字，将其擦除，然后写回值`ceil((a+b)/2)`。 

恰好之后`n-1`操作只剩下一个数字。 我们的任务不仅是使最终数字尽可能小，而且还要输出实现该最小值的操作序列。 

输入包含多个测试用例。 对于每个测试用例，我们都会得到一个整数`n`，意味着棋盘最初包含数字`1, 2, ..., n`。 输出必须首先包含可能的最小最终值，然后是每个操作中选择的精确对。 

约束条件是所有的总和`n`至多是`2·10^5`非常重要。 这意味着我们可以承担每个测试用例和输出的线性工作`n-1`运营。 任何尝试搜索不同操作序列的解决方案都是不可能的，因为可能的序列数量呈爆炸性增长。 甚至`n = 20`已经拥有天文数字的可能性。 

该问题有趣的部分是操作向上舍入。 向上舍入往往会使值大于正常平均值。 粗心的策略很容易留下比必要的更大的最终答案。 

一种边缘情况是`n = 2`。 

输入：```
1
2
```唯一可能的操作是：```
1 2
```产生`ceil(3/2)=2`。 答案是`2`。 

另一个边缘情况是有人首先重复组合最小的数字。 为了`n = 4`：```
1,2,3,4
```组合`1`和`2`给出`2`，然后结合`2`和`3`给出`3`，然后结合`3`和`4`给出`4`。 最终答案变成`4`，远非最佳。 

第三个微妙的案例很大`n`。 操作序列仍然必须有效地生成，因为输出本身包含`n-1`线。 与不可避免的输出成本相比，任何比每个测试用例线性慢的解决方案都会浪费时间。 

## 方法

 暴力方法将在每一步探索所有可能的对，并递归地尝试每个操作序列。 这是正确的，因为它最终会检查所有可能的结果。 不幸的是，它几乎立即变得无用。 开始于`n`数字，第一步有`n(n-1)/2`选择，下一步行动有`(n-1)(n-2)/2`选择等等。 搜索空间呈超指数增长。 

关键的观察来自于理解操作的作用。 由于我们计算$$\left\lceil \frac{a+b}{2} \right\rceil,$$结果总是介于`max(a,b)`大约是总和的一半。 如果我们反复将大量数字合并在一起，它们就会缩小。 例如：$$\left\lceil \frac{8+7}{2} \right\rceil = 8.$$两个大数会成为接近它们的数，而不是更大的数。 

假设我们总是取当前最大的数字并将其与第二大的数字合并。 开始于`n`，这会逐渐将最大值拉低，同时不允许小值使结果膨胀。 

例如，对于`n=4`：```
4,3 -> 4
4,2 -> 3
3,1 -> 2
```最终答案变成`2`，这是最优的。 

官方解决方案证明了一个值得注意的事实，即该策略总是产生尽可能小的最终值。 最终的数字总是`2`对于每一个`n ≥ 2`。

 ## 算法演练

 1. 从最大的数开始`cur = n`。 
2. 对于每个值`x`从`n-1`下降到`1`，记录操作`(cur, x)`。 
3. 更换`cur`经过：$$cur = \left\lceil \frac{cur+x}{2} \right\rceil$$这模拟了合并两个最大的可用数字后剩余的值。 

1. 继续下去，直到只剩下一个值。 
2. 输出最终值和所有记录的操作。 

这样做的原因是，在每一步中，我们都会将当前最大值与下一个最大的未使用值合并。 大数字是唯一能够保持最终答案较大的数字，因此我们首先积极减少它们。 

### 为什么它有效

 设当前最大值为`M`。 任何涉及较小数字的操作都会离开`M`没有变化，这意味着该板仍然蕴藏着非常大的价值。 如果我们希望最终结果变得尽可能小，我们必须尽可能地不断减少最大值。 

操作$$\left\lceil \frac{M+x}{2} \right\rceil$$下一个最大的可用`x`给出最大可能的最大减少，同时仍然消耗大量数字之一。 重复此过程会创建可实现的最小值的最小轨迹。 结果序列始终结束于`2`，这是可能的最小最终值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n = int(input())
        
        ops = []
        cur = n
        
        for x in range(n - 1, 0, -1):
            ops.append((cur, x))
            cur = (cur + x + 1) // 2
        
        print(cur)
        for a, b in ops:
            print(a, b)

solve()
```变量`cur`表示处理迄今为止看到的最大值后幸存的数字。 最初是`n`，板上最大的数字。 

每次迭代记录之间的操作`cur`以及下一个最大的未使用值。 表达式```
(cur + x + 1) // 2
```计算上限`(cur+x)/2`使用整数运算。 

操作顺序很重要。 我们必须处理来自`n-1`下降到`1`。 颠倒此顺序会产生更大的最终值。 

对于大数字不需要特殊处理，因为所有值都保持在 Python 的整数范围内。

import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

        n = int(input())

            cur = (cur + x + 1) // 2

 ## 边缘情况

 考虑：```
1
2
```该板仅包含`1`和`2`。 唯一的操作是：```
(1,2) -> 2
```算法输出`2`，这是最优的，因为不存在替代方案。 

考虑：```
1
3
```该算法执行：```
(3,2) -> 3
(3,1) -> 2
```并结束于`2`。 诸如合并之类的幼稚策略`(1,2)`首先产生：```
2,3
```然后变成`3`，更糟糕的结果。 

考虑：```
1
5
```该算法不断减少最大值：```
5 -> 5 -> 4 -> 3 -> 2
```不变的是每次操作都以当前最大剩余值为目标。 因为最大值控制着最终的答案，所以每次有机会减少它都会导致最佳的最终结果。
