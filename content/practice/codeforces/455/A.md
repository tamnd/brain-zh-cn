 ## 解决方案
 ## 问题理解

 我们得到一个整数数组。 在一步中，我们选择一个值`x`当前存在的，赚取`x`删除它的一次出现以及所有出现的点`x - 1`和`x + 1`结果从数组中消失。 

乍一看，该操作似乎取决于数组中的各个位置。 它实际上仅取决于值。 每当我们决定该值时`x`值得采取，每一次发生`x`最终可以被收集，因为移除一个`x`不删除其他`x`价值观。 唯一的冲突是与邻近价值观的冲突`x - 1`和`x + 1`。 

输入最多包含`10^5`数，且每个数最多为`10^5`。 任何试图直接探索不同动作序列的解决方案都是没有希望的。 即使二次算法也需要大约`10^10`最坏情况下的操作，远远超出了极限。 我们需要一些接近线性或`O(M)`， 在哪里`M`是数组中出现的最大值。 

一些边缘情况很容易被错误处理。 

考虑：```
3
2 2 2
```正确答案是`6`。 

粗心的解决方案可能会认为选择价值`2`只给出`2`点一次。 实际上，在删除相邻值后，所有三个出现的`2`仍然可以采取，屈服`2 + 2 + 2 = 6`。 

考虑：```
4
1 1 2 2
```正确答案是`4`。 

全部拿走`1`s 给出`2`点。 全部拿走`2`s 给出`4`点。 我们不能两者兼而有之，因为价值观`1`和`2`冲突。 任何独立处理事件而不是对相等值进行分组的解决方案都会产生错误的结果。 

考虑：```
5
1 3 5 7 9
```正确答案是`25`。 

没有一个值是相邻的，因此每个值都可以取。 仅比较相邻数组位置而不是相邻数值的解决方案将错过这一点。 

## 方法

 最直接的想法是思考每一个可能的动作顺序。 在每一步中，我们选择一个值，删除冲突的值，然后继续递归。 这是正确的，因为它探讨了所有法律结果。 

问题在于可能性的数量。 高达`10^5`元素，搜索空间变得巨大。 即使记住状态也是不切实际的，因为其余的值集可能会以太多方式变化。 

关键的观察是位置根本不重要。 只有价值频率才重要。 

假设值`x`出现`cnt[x]`次。 如果我们决定使用价值`x`，我们最终可以收集到```
x * cnt[x]
```点。 

做出决定后，价值观`x - 1`和`x + 1`变得不可用。 其他一切都不受影响。 

这将问题转化为一个简单得多的问题。 对于每个整数值`x`，我们有一所值得的“房子”```
points[x] = x * cnt[x]
```如果我们带房子`x`，我们不能拿走房子`x - 1`或者`x + 1`。 

这与经典的强盗动态规划问题的结构完全相同。 

让`dp[i]`是使用以下值可获得的最高分数`1`通过`i`。 

为了价值`i`，只有两种可能。 

如果我们跳过它，答案仍然存在`dp[i - 1]`。 

如果我们接受它，我们就会获得`points[i]`并且必须跳过`i - 1`, 给予```
dp[i - 2] + points[i]
```所以递归式变为：```
dp[i] = max(
    dp[i - 1],
    dp[i - 2] + points[i]
)
```这将问题简化为值空间上的简单线性动态规划。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳DP | O(M)| O(M)| 已接受 |

 这里`M`是输入中出现的最大值，最多`100000`。 

## 算法演练

 1. 读取数组。 
2. 计算每个值出现的次数。 
3. 对于每个值`x`，计算其总贡献：```
points[x] = x * cnt[x]
```如果我们选择价值`x`，这是我们可以从所有出现的情况中获得的总分`x`。 
4.让`mx`是数组中的最大值。 
5.创建一个大小为DP的数组`mx + 1`。 
6. 设置：```
dp[0] = 0
dp[1] = points[1]
```7. 对于每个值`i`从`2`到`mx`，计算：```
dp[i] = max(
    dp[i - 1],
    dp[i - 2] + points[i]
)
```第一个选项跳过值`i`。 

第二个选项有价值`i`，所以值`i - 1`不能使用。 
8. 输出`dp[mx]`。 

### 为什么它有效

 将相等的数字分组后，每个值`i`成为有奖励的独立决定`points[i]`。 唯一的限制是不能同时选择相差一的值。 

计算时`dp[i]`，每个有效的解决方案超过值`1..i`要么排除`i`或包含它。 如果排除的话`i`，最好的成绩正是`dp[i-1]`。 如果它包括`i`， 然后`i-1`必须排除，留下最好的分数`dp[i-2] + points[i]`。 这些是唯一的可能性，复发会选择更好的一种。 

通过感应`i`,`dp[i]`始终存储高达以下值的最佳答案`i`， 所以`dp[mx]`是整个问题的最优答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    mx = max(a)

    points = [0] * (mx + 1)
    for x in a:
        points[x] += x

    if mx == 1:
        print(points[1])
        return

    dp = [0] * (mx + 1)
    dp[1] = points[1]

    for i in range(2, mx + 1):
        dp[i] = max(dp[i - 1], dp[i - 2] + points[i])

    print(dp[mx])

if __name__ == "__main__":
    solve()
```第一阶段汇总所有相等的值。 该实现不是单独存储频率然后相乘，而是直接累加`x`进入`points[x]`对于每一次发生。 处理完数组后，`points[x]`已经等于`x * cnt[x]`。 

动态编程数组按值索引，而不是按原始数组中的位置索引。 这是该解决方案的中心思想。 递归仅取决于前两个值状态。 

特殊处理为`mx == 1`避免访问`dp[1]`否则 DP 数组的大小为 1。 这是唯一需要明确注意的边界条件。 

Python 整数自动处理大值。 最大可能的答案大约是`10^10`，它很容易适合 Python 的整数类型。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(M)| 从 1 到最大值的每个值都有一个 DP 转换 |
 | 空间| O(M)| 数组`points`和`dp`尺寸的`M + 1`|

 自从`M ≤ 100000`，该算法仅执行大约十万个 DP 转换，并且很容易满足时间和内存限制。

 ## 边缘情况

 考虑：```
3
2 2 2
```总分是：```
points[2] = 6
```DP 计算：```
dp[1] = 0
dp[2] = max(0, 6) = 6
```输出是`6`，正确收集每一次出现的值`2`。 

考虑：```
4
1 1 2 2
```总数变为：```
points[1] = 2
points[2] = 4
```DP 计算：```
dp[1] = 2
dp[2] = max(2, 4) = 4
```输出是`4`。 该算法正确地识别出所有`2`s 比全部都好`1`s。 

考虑：```
5
1 3 5 7 9
```总数为：```
points[1] = 1
points[3] = 3
points[5] = 5
points[7] = 7
points[9] = 9
```所有中间值的贡献为零。 递归重复获取每个不冲突的值，产生：```
1 + 3 + 5 + 7 + 9 = 25
```输出是`25`，表明数值之间的差距是由 DP 自然处理的。
