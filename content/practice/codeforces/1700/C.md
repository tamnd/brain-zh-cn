 ## 解决方案
 ## 问题理解

 我们有一个整数数组，代表树木路径上的土壤湿度水平。 每个值可以是正数、负数或零，我们的目标是使用三种操作将所有值减少为零：将前缀减一，将后缀减一，或将整个数组加一。 任务是确定实现零数组的此类操作的最小数量。 

数组大小`n`可以达到200,000，所有的总和`n`所有测试用例也限制为 200,000 个。 这意味着我们无法承担每个测试用例执行超过大约 O(n) 工作的算法； 任何二次或更糟糕的事情都太慢了。 湿度值的大小可能非常大，在任一方向都可达 10^9，这排除了尝试单独模拟每个增量或减量的方法。 

非明显边缘情况包括所有值均为负值、正值和负值交替出现或极值出现在边界处的数组。 例如，一个数组`[-3, -2, -5]`只需要在整个数组上增加即可达到零，而像这样的混合数组`[5, -5, 5, -5]`需要仔细拆分前缀和后缀操作。 仅从左到右扫描一次的简单方法会失败，因为它无法解释通过全局增加操作“推送”负值的需要。 

## 方法

 蛮力方法在概念上很简单。 对于每个操作，您扫描数组，查找具有非零值的前缀或后缀，并应用减量（或全局操作的增量）。 每个操作都会将某些值减一，然后重复操作，直到所有值都为零。 这是可行的，因为允许的操作足以将任何整数模式操作为零。 但这种方法太慢了：如果我们有`n = 2 * 10^5`和最大值`10^9`，模拟操作的数量将达到数十亿，这在2秒内是不可能的。 

最佳解决方案的关键见解来自于根据连续元素之间的差异来处理操作。 如果我们查看从一个位置到下一个位置所需的变化，我们可以将总移动量表示为每一步所需的正增加和所需的正减少之和。 具体来说，最小移动次数是第一个元素的绝对值加上从左到右移动时所有正差值之和，加上从右到左移动时所有负差值之和。 这是有效的，因为每个前缀/后缀操作都可以被解释为有效地“吸收”差异。 

本质上，相邻元素之间的每次局部增加或减少都可以通过单个前缀或后缀操作来满足，而全局增加操作处理负起始值。 通过在单遍中累积这些差异，我们可以避免模拟并将问题减少到 O(n) 时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n * 最大( | a_i | )) |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，请阅读`n`和数组`a`。 
3. 初始化计数器`actions`为零。 这将跟踪所需的总操作。 
4. 第一步是处理第一个元素。 如果`a[0]`是负数，我们需要`-a[0]`在整个数组上增加； 如果是积极的，我们需要`a[0]`通过前缀操作减少。 将其添加到`actions`。 
5. 从索引 1 到 n-1 循环遍历数组。 对于每个元素`a[i]`，计算差值`diff = a[i] - a[i-1]`。 如果`diff > 0`，表示相对于前一个元素需要额外增加，可以通过前缀操作来实现。 如果`diff < 0`，它表示可以通过后缀操作实现的额外减少。 添加绝对值`diff`到`actions`。 
6. 完成循环后，`actions`包含将数组归零所需的最少操作数。 
7. 打印`actions`对于每个测试用例。 

为什么它有效：我们计算的每个操作都对应于纠正连续元素之间的斜率所需的最小工作单元。 前缀和后缀操作自然地与正负差异对齐，而全局增加处理最初的负起点。 这个不变量保证不会计算多余的移动。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        actions = abs(a[0])  # handle the first element
        for i in range(1, n):
            diff = a[i] - a[i-1]
            actions += abs(diff)
        print(actions)

if __name__ == "__main__":
    solve()
```代码初始化`actions`与第一个元素的绝对值，反映从零开始的最小操作计数。 然后，循环累积连续元素之间所有斜率的成本。 使用`abs`确保我们同时计算正调整和负调整，并且单个循环使每个测试用例的复杂度为 O(n)。 从索引 1 开始可以避免边界错误。

 ## 边缘情况

 对于像这样的严格负数数组`[-3, -2, -5]`,`actions`第一个元素从 3 开始。 那么差异是`(-2)-(-3)=1`和`(-5)-(-2)=-3`，所以我们添加`1 + 3 = 4`总共为 7。这反映了 3 个全局增加加上斜率之间的调整，正确地将阵列归零。 

对于交替数组`[1, -2, 3, -4]`，我们计算`abs(1)=1`，然后差异`-3, 5, -7`，添加`3+5+7=15`总共 16 个。每个步骤都捕获前缀和后缀操作所需的精确移动，无需模拟。 

这证实了该算法能够一致地处理边界差异、混合符号和极值。
