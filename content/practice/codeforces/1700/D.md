 ## 解决方案
 ## 问题理解

 该系统是一系列容器，每个容器都有固定的容量。 水以每个打开的管道每秒一个单位的恒定速率进入这些容器的选定子集。 每当一个容器溢出时，多余的部分会立即推送到下一个容器，这种级联会继续下去，直到最后一个容器，溢出离开系统。 

目标不是直接模拟水流，而是选择容器的子集作为水源激活。 对于每个查询，我们都有一个时间限制，并且必须确定要激活的最小源数量，以便从空开始，每个容器不迟于该时间达到满容量。 

关键的相互作用是水不会停留在本地。 在位置 i 打开管道不仅有助于容器 i，还可能通过溢出影响右侧的所有容器。 这使得贡献具有很强的非局部性，并强制对前缀结构而不是独立能力进行推理。 

这些约束推向接近 O(n log n) 或 O(n log^2 n) 的解决方案。 由于多达 200,000 个锁和 200,000 个查询，任何每个查询的线性模拟或天真的贪婪重新计算都会超出时间限制几个数量级。 该解决方案必须对结构进行一次预处理，并在对数时间内回答每个查询。 

当早期的锁与后来的锁相比具有较大的容量时，就会出现微妙的边缘情况。 例如，如果 v = [10, 1, 1] 并且时间很短，则在后面的锁中打开管道无助于填充第一个锁，因为溢出无法向后传播。 优先考虑小后缀位置的幼稚策略会错误地假设稍后的激活会补偿早期的缺陷。 另一个极端情况是当时间小于最大 v_i 时； 即使打开所有管道也无法及时填充最大的锁，因此答案必须立即为-1。 

## 方法

 如果我们修复打开管道的 k 个数量，问题就变成检查是否存在 k 个索引的选择，以便所有锁都可以在 t 秒内被填充。 强力解决方案将尝试所有大小为 k 的子集并模拟每种配置的水流。 原则上这是正确的，因为一旦源固定，该过程就是确定性的，但它会组合爆炸。 子集的数量是 O(n 选择 k)，即使限制 k 也不能阻止查询之间的指数增长。 

思考系统的一个更有用的方法是颠倒视角。 不要跟踪水如何向前流动，而是考虑一下在时间 t 之前将水闸 i 填满意味着什么。 每个在位置 j 处打开的管道最多贡献 t 个单位的水，并且由于溢流结构，任何到达位置 i 的单位都必须通过所有中间水闸。 这会产生瓶颈效应：填充前缀取决于有多少源位于该前缀或之前。 

关键的观察是，系统的行为就像我们为每个打开的管道分配 t 个“预算”单位，并且这些预算可以向前传送，但不能向后传送。 为了使所有锁都满，我们需要足够的总贡献来满足容量引起的前缀需求。 最佳策略总是倾向于将管道放置在尽可能远的右侧，因为它们有助于减少早期约束，同时仍然通过饱和间接通过向左溢出来做出贡献。 

这将问题简化为对固定 k 的贪婪可行性检查，并且由于 k 中的可行性是单调的，因此我们可以对每个查询的答案进行二分搜索。 预计算前缀信息允许以线性时间或稍微优化的形式完成每次检查，根据实现产生总体 O((n + q) log n) 或 O((n + q) log^2 n) 解决方案。

 | --- | --- | --- | --- |
 | 暴力子集 | 指数| O(n) | 太慢了 |
 | 贪心+二分查找| O((n + q) log n) | O((n + q) log n) | O(n) | 已接受 |

 ## 算法演练

 我们将任务重新表述为决策问题：对于固定时间 t 和固定数量 k 的管道，决定是否可以选择保证所有锁都被填充的 k 个位置。 

1. 对于给定的 t，计算每个管道可以贡献多少。 由于每个打开的管道产生 t 个单位，因此每个选定的位置最多贡献 t 个总单位的流量，最终将通过溢出进行分配。 这使得系统只需选择 k 个源，每个源的容量为 t。 
2. 从左向右遍历船闸，同时保持仍必须供应多少水才能满足每个船闸的要求。 在位置 i，我们跟踪 v_i 的剩余需求。 
3. 当管道在位置 i 处打开时，它会贡献 t 个单位，有助于满足当前和未来的需求。 贪婪的想法是在需要时尽早使用管道来弥补出现的赤字，因为拖延只会带来增加以后所需补偿的风险。 
4. 保持来自已选定管道的可用水的持续剩余。 当我们到达锁 i 时，我们从这个盈余中减去它的要求 v_i。 如果盈余变为负值，我们就被迫在 i 之前或 i 时激活另一个管道来进行补偿。 
5. 每次我们被迫打开一个管道时，我们都将其放置在当前位置，将 t 添加到剩余部分，然后继续。 计算需要多少个这样的强制打开。 
6. 如果在任何时候所需的开口数量超过 k，则该配置是不可能的。 否则的话，也是可行的。 
7. 对于每个查询，二分搜索使配置可行的最小 k。 

关键的不变量是，在每个前缀 i 处，假设采用最佳放置策略，算法使用迄今为止放置的所选管道数量来维持可实现的最大可能剩余水剩余量。 每当贪婪过程被迫放置管道时，这是因为没有更早的放置可以防止该前缀处的赤字。 这使得每个位置都是局部最优且全局必要的。 由于可行性仅取决于我们是否可以避免负剩余，因此贪心构造正确地表征了 k 根管道是否足够。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can(v, t, k):
    n = len(v)
    used = 0
    surplus = 0

    i = 0
    while i < n:
        if surplus < v[i]:
            used += 1
            if used > k:
                return False
            surplus += t
        surplus -= v[i]
        i += 1

    return True

def solve():
    n = int(input())
    v = list(map(int, input().split()))
    q = int(input())
    queries = [int(input()) for _ in range(q)]

    max_v = max(v)

    for t in queries:
        if t < max_v:
            print(-1)
            continue

        lo, hi = 1, n
        ans = n

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(v, t, mid):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        print(ans)

if __name__ == "__main__":
    solve()
```核心实现分为两部分。 功能`can`使用单次从左到右的扫描检查固定时间和管道数量的可行性，模拟当前打开的管道可以满足多少剩余需求。 二分查找在`solve`找到通过此可行性测试的最小数量的管道。 

初步检查`t < max(v)`防止不必要的工作，因为即使集中所有流量也无法比其自身的容量要求更快地填充最大的锁。 贪婪逻辑依赖于维持不断的盈余，该盈余代表了先前打开的管道中剩余的“未使用的水潜力”，并且每次变得不足时，都被迫安装新的管道。

 ## 边缘情况

 关键的边缘情况是时间限制小于最大锁定容量。 对于 v = [10, 1, 1] 且 t = 5，没有任何数量的管道可以满足第一个锁定，因为即使完全专用的管道也无法在给定持续时间内每秒提供足够的水。 该算法通过拒绝所有 k 的可行性检查立即处理此问题。 

另一个微妙的情况是容量急剧下降。 对于 v = [5, 1, 1, 1]，尽早放置所有管道似乎是最佳选择，但贪婪程序表明，无论早期集中度如何，后来的赤字都会迫使额外的开口。 盈余机制正确反映了早期的盈余不能向后重新分配，确保在需要时准确计算额外的管道。 

第三种情况是 n = 1。如果 t < v1，则答案为 -1，否则为 1。 二分搜索和贪婪逻辑自然会崩溃到这一点，而无需超出最大检查范围的特殊外壳。
