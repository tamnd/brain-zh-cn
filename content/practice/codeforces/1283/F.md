 ## 解决方案
 ## 问题理解

 我们有一棵树$n$顶点，其中每个顶点代表一盏灯。 其中一盏灯直接连接到电源，电力通过树的电线形成的直接连接从电源传播。 每根电线都有一个隐含的方向：一个端点距离光源（主灯）较近，另一个端点较远（辅助灯）。 

每盏灯$i$有重量$2^i$，这使得较高指数的灯比较低指数的灯更重要。 如果我们移除一根电线，树就会分成两个组件，并且该电线的“重要性”被定义为当该电线被切断时与电源断开的组件中所有顶点的权重之和。 换句话说，当该边被删除时，子树的总权重将失去对根的访问权。 

棘手的部分是我们没有得到那棵树。 相反，我们得到一个序列$a_1, a_2, \dots, a_{n-1}$， 在哪里$a_i$是主要终点$i$- 最重要的电线，严格按照重要性降序排列。 根据这个排序和这些“主要端点”，我们必须重建任何可以产生这种排序的有效有根树。 

约束条件很大，有$n \le 2 \cdot 10^5$，因此任何尝试显式枚举可能的树或重新计算子树权重的方法都会太慢。 需要线性或近线性结构。 

一个关键的结构困难是权重是二的幂。 这使得子树和的行为类似于二进制表示：每个子树和都由其内部的顶点集唯一确定，并且子树和之间的比较对应于首先按字典顺序比较最大标签。 

一种简单的方法是尝试所有可能的根并尝试贪婪地重建边缘，同时验证诱导的重要性排序。 这将涉及在每个暂定边缘之后重新计算子树总和，这会导致$O(n^2)$或更糟糕的行为，并且是不可能的$2 \cdot 10^5$。 

如果假设序列$a_i$直接编码父子关系。 事实并非如此。 例如，同一个顶点可以出现多次$a$，这意味着它是多条边的主要端点，并且这些边属于树结构的不同部分。 任何治疗方法$a_i$作为父数组，在这种情况下会立即中断。 

## 方法

 解决这个问题的关键是反转具有指数权重的树中重要性的表现方式。 

因为权重是$2^i$，比较两个子树和相当于比较每个子树中存在的最大索引。 这意味着每个切割边的重要性主要由分离组件中标记最高的顶点决定。 

现在解释给定的序列$a_i$作为以“断开侧”上的最大标签的降序描述边缘。 子树中出现的最大标签完全主导了它的贡献，因此构造被迫尊重层次结构，其中更高的标签必须在分离过程中“更早”出现。 

这提出了一种贪婪的重建策略：我们以递增的顺序逐渐附加顶点，同时确保当一个顶点作为主要端点出现时，它成为新形成的附加区域的代表。 

我们维护一组由仍然可以接受附件的顶点表示的“活动组件”。 最初，最高索引的顶点充当自然锚，因为它支配包含它的所有子树和。 

每次我们处理一个值$a_i$，我们将其解释为强制建立新的连接，其中新的顶点附加在$a_i$，消耗一个可用的“槽”$a_i$。 这种排序保证了当我们遇到一个顶点时，之前已经创建了足够的容量，以便它可以作为父节点，其出现的次数与它出现的次数完全相同。 

这将问题简化为有根树上的度平衡构造，但问题在于没有给出根。 我们将根确定为永远不会作为“子需求”出现的顶点，从而强制稍后附加它，实际上是在所有分配后具有剩余容量的顶点。 

成功的构建可以简化为构建一棵符合多组父级需求的树，其中每个外观$a_i$对应于在该顶点下分配的一个子槽。 当且仅当我们始终可以将新节点附加到具有剩余容量的某个较早的顶点时，排序才能确保可行性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 通过子树重新计算进行暴力重建 |$O(n^2)$|$O(n)$| 太慢了|
 | 基于贪婪容量的重构 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将序列转换为将父节点分配给节点的构造过程。 

1. 统计每个顶点在数组中出现的次数$a$。 这表示重建树中每个顶点最终必须有多少个子节点。 这是可行的，因为每个外观都对应于一条边，其中该顶点是主要端点。 
2. 创建所有顶点的列表，并以允许我们逐步分配子项的方式排序。 我们将使用“可用父母”队列，最初是空的。 
3. 将候选根确定为除了构造约束所隐含的范围外永远不需要作为子项附加的任何顶点。 在实践中，我们确保在所有分配之后，恰好有一个顶点具有未使用的容量。 
4. 我们以标签递增的顺序迭代顶点，将每个新顶点视为必须附加到先前可用的父顶点的东西。 
5. 对于我们引入的每个顶点，我们将其连接到仍具有剩余容量的当前可用的父顶点。 父级的选择由序列顺序决定：我们总是使用最早的未解决的需求，确保我们遵循重要性递减的顺序。 
6. 将子项分配给父项后，我们会减少该父项的剩余容量。 如果仍有剩余容量，则仍可用于将来的附件； 否则，它将从可用集中删除。 
7. 如果在任何时候我们需要分配一个父级但没有可用的父级，则构造是不可能的，我们输出$-1$。 

处理完所有顶点后，边定义了一个有效的有根树，任何从未被强制作为子节点但仍具有剩余容量的顶点都可以作为根。 

### 为什么它有效

 正确性来自于每个顶点出现的事实$a$定义必须充当主要端点的确切边数。 由于权重是 2 的幂，因此边的排序相当于按分离组件中最大标签的降序强制执行约束。 这迫使贪婪的消费模型：较高标签的顶点必须“吸收”附件，然后较低的标签才能影响结构。 

该算法保持了不变性，即在每一步中，仍然可以附加所有未处理的顶点，而不会违反所需的父频率。 由于我们总是将下一个顶点附加到当前可行的父顶点，因此我们永远不会破坏序列隐含的所需度数约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 2:
        print(1)
        print(1, 2)
        return
    
    cnt = [0] * (n + 1)
    for x in a:
        cnt[x] += 1

    import heapq

    # available parents: (-remaining_capacity, node)
    heap = []
    edges = []

    # we will process nodes 1..n, maintaining a pool of available parents
    # initially, no edges are assigned; we add nodes gradually
    ptr = 1

    # function to push node into heap if it has capacity
    def add_node(u):
        if cnt[u] > 0:
            heapq.heappush(heap, (-cnt[u], u))

    # start by adding the first possible parent candidates
    for i in range(1, n + 1):
        add_node(i)

    # we will construct a spanning tree by greedily connecting nodes
    # ensure we always have a parent available different from current node
    for v in range(1, n + 1):
        # remove self from being parent candidate if present
        while heap and heap[0][1] == v:
            heapq.heappop(heap)

        if not heap:
            print(-1)
            return

        negc, u = heapq.heappop(heap)
        edges.append((u, v))
        cnt[u] += negc + 1  # decrement capacity

        if cnt[u] > 0:
            heapq.heappush(heap, (-cnt[u], u))

    # check connectivity (implicitly n-1 edges built)
    if len(edges) != n - 1:
        print(-1)
        return

    # choose root as node that never appears as child in this construction
    is_child = [False] * (n + 1)
    for u, v in edges:
        is_child[v] = True

    root = 1
    for i in range(1, n + 1):
        if not is_child[i]:
            root = i
            break

    print(root)
    for u, v in edges:
        print(u, v)

if __name__ == "__main__":
    solve()
```该代码实现了贪婪容量解释。 每个顶点开始时的配额等于它在列表中出现的次数，每次我们将其指定为父顶点时，我们都会消耗该配额的一个单位。 

堆维护仍然可以作为父节点的所有顶点。 对于每个新顶点$v$，我们选择一个有效的父母$u$那不是$v$本身。 这可以避免自循环并确保有效的树结构。 使用父项后，我们更新其剩余配额，如果它仍然可以接受子项，则重新插入它。 

一个微妙的点是，事先并不知道根。 我们在将边构建为任何从未作为子项出现的顶点后将其重建，因为该顶点必须保持与其上方的任何物体相连。

 ## 边缘情况

 当一个顶点出现太多次时，就会出现关键的边缘情况$a$与一棵树所能承受的重量相比。 例如，如果$n=3$和$a = [1,1]$，顶点 1 需要两个传出父角色，但仅存在其他两个顶点。 当堆在容量耗尽后无法提供足够的不同附件时，算法会检测到这一点，从而导致失败。 

另一个微妙的情况是，在某个步骤中唯一可用的父节点是当前节点本身。 这将创建一个自循环，这在树中是无效的。 从候选堆中显式删除当前节点可以防止这种情况，从而确保结构保持非循环状态。 

最后一种结构情况是当根不明显时。 在多个顶点永远不会成为子顶点的配置中，算法选择任何此类顶点作为根。 由于所有边在最终输出中都是无向的，因此任何此类选择都会产生与原始过程一致的有效有根解释。
