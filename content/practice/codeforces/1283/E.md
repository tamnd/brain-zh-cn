 ## 解决方案
 ## 问题理解

 我们给定一组人，他们被放置在一条线上的整数点上。 每个人从一个固定的坐标开始，最多可以向左移动一步、留在原地或向右移动一步。 当每个人都做出选择后，多个人可能最终会出现在同一个坐标上，而我们只关心最终配置中占据了多少个不同的坐标。 

任务是确定所有有效移动分配的两个极端。 首先，占用位置的最小可能数量，这对应于在移动规则允许的情况下尽可能紧密地聚集人员。 其次，占据的位置的最大可能数量，这对应于在不违反“最多移动一个”约束的情况下尽可能分散它们。 

限制允许最多 200,000 人。 这个大小排除了任何试图枚举所有移动组合或模拟所有分配的解决方案，因为每个人都有三种选择，暴力会呈指数级爆炸。 即使是在二次时间内重复扫描数组的贪婪结构也会太慢，因此任何有效的方法在排序后都必须本质上是线性的或接近线性的。 

当多人从同一位置或连续位置开始时，会出现微妙的边缘情况。 例如，如果所有人都在位置 2，则他们只能分散到位置 1、2 和 3，因此即使 n 可能很大，最大的不同计数也是 3。 另一方面，当位置已经很好地分开时，例如 [1, 3, 5]，最小值已经接近最大值，因为重叠的可能性不大。 

另一个角点情况是边界位置 1 和 n，其中移动可以将人推至 0 或 n+1。 这些额外的位置是有效的端点，仅对最大情况有效，在这种情况下，我们希望通过使用边界处的可用松弛来避免碰撞。 

## 方法

 蛮力视图很简单：对于每个人，选择三个位置之一并计算结果集的大小。 这正确地探索了整个解空间，但是配置的数量是 3^n，对于 n 高达 200,000 来说这是完全不可行的。 即使 n 约为 20，它也变得临界。 

关键的观察结果是该结构本质上是具有有限位移的一维堆积。 一旦位置被排序，碰撞和分离仅取决于相邻值之间的局部相互作用。 这使得可以按顺序处理数组并在本地决定如何分配最终位置。 

对于最大情况，我们希望避免重叠，因此每个人都尝试占据唯一的整数位置。 由于每个原始位置 x_i 都允许 [x_i - 1, x_i + 1] 中的最终值，因此我们可以贪婪地分配位于该区间内的最左边可能的空闲位置。 这是在一条线上安排间隔的经典想法：每个人贡献一个间隔，我们在其中选择不同的点。 

对于最小情况，我们扭转直觉。 我们不想分散，而是希望合并尽可能多的点。 问题归结为形成尽可能少的不同“簇”，其中每个簇对应于一个连续的整数段，由于 ±1 的灵活性，这些整数可以吸收多个点。 排序时，我们可以贪婪地尝试尽可能远地扩展当前簇； 如果下一个点不能被吸收，我们开始一个新的簇。 

排序后，两种解决方案都变成线性的，因为每个元素都被处理一次，并且决策仅取决于最后选择的位置或簇边界。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(3^n) | O(3^n) | O(n) | 太慢了|
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

我们首先对位置数组进行排序，以便我们能够一致地推理邻居。 

### 最大占用房屋数

 1. 初始化变量`last`到一个非常小的值，表示最后占用的位置。 
2. 迭代排序后的位置。 
3. 对于每个位置`x`，考虑允许的间隔`[x-1, x+1]`。 
4. 选择该区间内严格大于的最小值`last`。 这确保我们不会重复使用前一个人已经获取的坐标。 
5. 如果存在这样的值，则赋值并更新`last`。 否则，请跳过此人。 

我们总是选择最小的可行值的原因是，过早消耗空间只会损害未来的选择。 延迟分配只会减少后续职位的可用空间。 

### 最小占用房屋数量

 1. 初始化变量`last_used`到一个非常小的值。 
2. 维护计数器`groups`从 0 开始。 
3. 迭代排序后的位置。 
4. 对于每个`x`，通过检查if来判断是否可以合并到当前组中`x-1 <= last_used + 1`。 
5. 如果是，通过设置扩展当前组`last_used = min(x+1, last_used + 1)`。 
6. 否则，开始一个新组并递增`groups`， 环境`last_used = x + 1`。 

这个想法是，每个组代表一个最大连续区域，其中所有选定的最终位置都可以通过 ±1 的灵活性重叠。 

### 为什么它有效

 对于最大情况，每次分配相当于在每个排序位置周围的单位间隔内放置一个点。 贪心规则始终选择最早的可用槽，这保留了最大的未来可行性，因为任何后续分配都无法从跳过较早的有效位置中受益。 

对于最小情况，该过程构建最大重叠段。 如果新点无法吸收到当前段中，则由于排序和有限位移，任何有效的分配都无法将其与较早的点合并。 因此，建立一个新的小组是被迫的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    # maximum number of distinct positions
    last = -10**18
    max_ans = 0

    for x in a:
        # try to assign x-1, x, or x+1
        for p in (x - 1, x, x + 1):
            if p > last:
                last = p
                max_ans += 1
                break

    # minimum number of distinct positions
    groups = 0
    last_used = -10**18

    for x in a:
        if x - 1 > last_used:
            groups += 1
            last_used = x + 1
        else:
            last_used = min(last_used, x + 1)

    print(groups, max_ans)

if __name__ == "__main__":
    solve()
```第一个循环通过贪婪地为每个人分配其允许范围内最早的可能自由坐标来构建最大值。 三个选项的内部循环是安全的，因为我们总是从左到右尝试，确保未来空间的消耗最小。 

第二个循环构建最小簇。 当下一个位置不能与当前可达段重叠时，必须开始一个新的组。 否则，该段将被扩展，跟踪最远的可到达合并点。 

在这两种情况下排序都是必不可少的； 没有它，邻接信息就毫无意义，贪婪的决策也会失败。

 ## 边缘情况

 当所有值都相同时，最小值会将所有值折叠成一个簇，而最大值则完全使用 ±1 自由度来分离所有点。 

当值已经很好地分离时，每个点都会形成自己的簇，并且两个答案都一致，从而确认该算法不会人为地合并独立组件。 

当值位于 1 或 n 等边界时，移动到 0 或 n+1 的能力可确保最大情况仍然可以保持分离，这是通过在所有位置上统一处理允许的间隔来自然处理的。
