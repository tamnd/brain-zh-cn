 ## 解决方案
 ## 问题理解

 我们在单位正方形的无限网格上移动。 我们可以从任何一个方格向上、向下、向左或向右移动一步。 有些方格被标记为坏方格，进入这样的方格需要花费 1 美元。 起始方格和结束方格保证是好的，因此答案只计算中间访问过的坏方格。 

一个正方形`(x, y)`如果它位于两个对角线系列之一上，则很糟糕：$|x+y|\equiv 0 \pmod{2a}$或者$|x-y|\equiv 0 \pmod{2b}$坐标和参数大为`10^9`，因此任何直接探索网格的算法都是不可能的。 即使沿着曼哈顿最短的路径行走也可能需要大约`2 * 10^9`移动。 该解决方案必须在恒定时间或对数时间内工作。 

关键的困难是理解这些坏细胞实际上的几何形状。 幼稚的解读表明危险细胞分散，但全等条件描述了整个对角条纹。 答案不是在网格上寻找路径，而是计算有多少条障碍线分隔两个区域。 

一些边缘情况很容易被错误处理。 

假设两个点位于同一安全区域内，例如：```
2 2 1 0 1 1
```答案是`0`。 如果粗心地计算有多少条坏对角线与点之间的矩形相交，就会错误地得出肯定的答案。 

当坐标为负时，会出现另一种微妙的情况：```
3 4 -10 -1 7 20
```恶劣条件使用绝对值。 如果我们忘记整数除法对于负数的表现，公式就会出错一。 解决方案必须谨慎使用楼层划分。 

当一个点正好位于一条坏线旁边时，还会出现边界问题。 考虑：```
2 2 1 0 0 1
```答案是`1`。 这两个点位于仅由一条坏对角线分隔的相邻区域。 如果我们使用普通除法而不是楼层逻辑错误地计算边界，我们可能会得到`0`或者`2`。 

最后一个重要的观察结果是，坏对角线的交点不会使答案增加两倍。 跨越一个相连的坏元件需要花费一次访问的时间，无论有多少坏单元接触那里。 单独处理对角线会导致计数过多。 

## 方法

 强力解释将每个网格方块建模为图顶点并运行 BFS 或 Dijkstra。 搬进一个好的广场需要花费`0`，进入坏方成本`1`。 由于网格是无限的，我们至少需要将自己限制在点周围的某个边界框内。 

从概念上讲，这是可行的，因为最短路径算法可以正确地最小化所有可能路线的总成本。 问题在于规模。 坐标可能相差数十亿，因此即使存储可到达的矩形也需要大约`10^18`最坏情况下的细胞。 任何图的遍历都是遥不可及的。 

坏细胞的结构提供了更强有力的观点。 方程涉及`x + y`和`x - y`，它们是对角坐标。 每个条件描述无限多条平行对角线。 这些线将平面划分为相连的安全区域。 

一个重要的几何事实是，从一个安全区域移动到另一个安全区域需要恰好穿过一条坏对角线一次。 由于坏单元本身形成区域之间的边界，因此访问的坏单元的最小数量就是分隔对角线障碍的最小数量。 

而不是推理`(x, y)`直接坐标，定义：$u=x+y$和$v=x-y$坏线变成竖线和横线`(u, v)`飞机：$u\equiv 0 \pmod{2a}$和$v\equiv 0 \pmod{2b}$安全区域是这些线之间的矩形单元。 如果两个点属于连续倍数之间的同一区间，则它们位于同一区域`2a`和`2b`。 

因此，答案归结为计算有多少区域边界将变换后的坐标分开。 这变成了一个简单的算术计算。

 ## 算法演练

 1. 将两个点变换为对角坐标：$u=x+y,\quad v=x-y$在这些坐标中，坏对角线变成轴对齐的网格线。 
2. 对于每个点，确定它属于图中的哪个水平条带`u`方向。 

我们通过楼层划分来做到这一点`2a`:$U=\left\lfloor \frac{u}{2a} \right\rfloor$每次我们越过一条不好的线`u = k * 2a`，该索引改变一。 
3. 对`v`方向使用`2b`:$V=\left\lfloor \frac{v}{2b} \right\rfloor$4. 跨越的坏区最少数量为：$\max\left(|U_1-U_2|, |V_1-V_2|\right)$跨越一个坏组件可以同时将两个坐标前进一。 因此，答案是最大差值，而不是总和。 
5. 打印结果。 

### 为什么它有效

 不良对角线将平面划分为相连的安全区域。 在变换后的坐标中`(u, v)`，这些区域是由垂直和水平坏线分隔的矩形。 

从一个矩形移动到另一个矩形会改变`u`条带索引或`v`每个交叉点最多将索引剥离一个。 对不良连接组件的单次访问可以在穿过交叉路口时同时调整两个坐标。 

这意味着任何路径必须至少`max(|ΔU|, |ΔV|)`交叉点，因为每个交叉点最多将每个坐标更改 1。 相反，当两个坐标仍需要调整时，我们总是可以通过策略性地穿过交叉点来构建一条恰好实现那么多交叉点的路径。 

因此下限和上限匹配，证明最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a, b, x1, y1, x2, y2 = map(int, input().split())

    u1 = x1 + y1
    v1 = x1 - y1

    u2 = x2 + y2
    v2 = x2 - y2

    du = abs(u1 // (2 * a) - u2 // (2 * a))
    dv = abs(v1 // (2 * b) - v2 // (2 * b))

    print(max(du, dv))

solve()
```第一部分将普通坐标转换为对角坐标。 这是核心的几何变换。 经过这样的改造，复杂的对角屏障就变成了普通的等距纵横线。 

下一部分计算每个点属于哪个条带。 使用楼层划分至关重要，因为坐标可能为负。 蟒蛇的`//`运算符已经执行了数学除法，这正是我们所需要的。 

答案不是`du + dv`。 这假设每次交叉仅改变一个坐标。 在坏对角线的交叉点处，一次交叉可以同时推进两个条带索引。 这就是为什么正确的公式使用`max`。 

该实现仅使用整数运算，因此即使接近整数也不存在精度问题`10^9`限制。

 ## 边缘情况

 考虑两个点位于同一安全区域内的情况：```
2 2 1 0 1 1
```我们计算：

 -`u1 = 1`,`u2 = 2`-`v1 = 1`,`v2 = 0`然后：

-`1 // 4 = 0`-`2 // 4 = 0`-`1 // 4 = 0`-`0 // 4 = 0`因此两个变换后的条带索引匹配，给出答案`0`。 没有坏的对角线将点分开。 

现在检查负坐标情况：```
3 4 -10 -1 7 20
```变换后的坐标为：

 -`u1 = -11`-`u2 = 27`使用楼层划分：

 -`-11 // 6 = -2`-`27 // 6 = 4`区别在于`6`。 

如果我们错误地截断为零，我们将得到`-1`而不是`-2`，产生答案`5`，这是错误的。 该算法成功是因为 Python 楼层划分与几何划分相匹配。 

最后，考虑边界邻居的情况：```
2 2 1 0 0 1
```改造后的`u`坐标保持在同一个条带中，但是`v`坐标从条带移动`0`剥去`-1`。 它们之间恰好有一条坏对角线，所以答案是`1`。 

这证实了带索引解释与网格的几何形状精确匹配。
