 ## 解决方案
 ## 问题理解

 我们得到了一个循环的曲目播放列表，每个曲目都有一个数字“酷”值。 从任何选定的曲目开始，我们继续按循环顺序向前收听，并根据需要重新访问曲目。 在聆听时，我们保持着迄今为止所见的最大程度的冷静。 

停止规则取决于此运行最大值。 当新播放的曲目的冷度严格低于当前最大值的一半时，聆听会立即停止。 从一首曲目开始的成本是我们在停止之前播放的曲目数量，计算循环结束时的重复访问次数。 

对于每个起始位置，我们必须计算我们持续聆听的时间，或者报告我们从未停止。 

关键限制是 n 最多可达 100,000，因此任何独立模拟每次启动的解决方案都会立即变得太慢。 每次启动的简单模拟将重新访问最多 O(n) 条轨道，导致 O(n^2) 工作，无法通过。 

微妙的困难在于，停止条件取决于我们前进时不断变化的全局最大值，因此该过程不是简单的固定阈值比较。 最大值可以稍后增加并放松约束，这使得天真的贪婪停止决策不正确。 

当几个步骤后最大值显着增加时，就会出现典型的边缘情况。 例如，如果我们从一个较小的值开始，我们最初可能希望快速停止，但稍后更大的值可以提高阈值并允许更多遍历。 这破坏了任何纯粹的局部推理。 

另一个棘手的情况是所有值都相等。 那么最大值永远不会改变，并且任何值都不会严格小于它的一半，因此行走永远不会停止，并且所有索引的答案都是 -1。 任何假设最终失败的解决方案都将错误地终止。 

## 方法

 蛮力方法很简单。 对于每个起始索引 i，我们模拟绕圈向前移动，更新迄今为止看到的最大值，并检查每一步的停止条件。 我们继续，直到返回 i 或停止规则触发。 

这是正确的，因为它完全反映了所描述的过程。 然而，在最坏的情况下，每个起始点在停止之前可能会遍历几乎整个数组，并且由于有 n 个起始点，这会导致 O(n^2) 转换。 当 n 达到 10^5 时，这远远超出了可行的限制。 

关键的观察结果是，该过程仅取决于在遇到相对于段中某个最大值而言太小的值之前我们可以延伸多远。 如果我们考虑从 i 开始的步行，则前缀上的最大值仅在我们达到新的最大值时才会增加，并且在最大值之间阈值是固定的。 这表明我们不应该一步一步地模拟，而应该在临界点之间跳跃。 

加速这种循环“下一个坏位置”查询的标准方法是为每个位置预先计算下一个索引，其中值相对于给定阈值变得“危险地小”。 由于阈值取决于分段最大值，因此我们通过构建一个结构来重构问题，该结构使我们能够在对数时间内重复跳转到下一个候选故障点。 这通常是使用线段树或稀疏表与双倍数组上的二进制提升相结合来实现的。 

我们复制数组以线性处理循环行为，并预先计算范围最大值。 然后，对于每个起始位置，我们模拟跳跃：在保持满足约束的同时，我们总是尽可能地延伸，对最远的可到达位置使用二分搜索，使所有元素至少为当前最大值的一半。 每次遇到新的最大值时，阈值就会增加，然后我们继续。 每次跳转都会跳过许多中间位置，从而将每次转换的复杂性降低到对数。

重要的结构思想是，只有当我们达到新的最大值时，该过程才能“改变状态”，并且这些事件足够稀疏，我们可以在它们之间有效地跳转。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了 |
 | 最优（线段树+双倍数组上的二分查找）| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们处理双倍数组`b`长度`2n`， 在哪里`b[i] = a[i]`和`b[i+n] = a[i]`。 这使我们能够将循环运动视为线性段。 

1. 建立一个范围最大的结构`b`，这样我们就可以高效地查询任意区间内的最大值。 这是必要的，因为决策取决于段中迄今为止看到的最大值，并且我们必须快速重新计算它。 
2. 对于每个起始位置`i`在原始数组中，初始化`pos = i`,`end_limit = i + n - 1`,`cur_max = 0`， 和`answer = 0`。 
3.同时`pos <= end_limit`，计算最远位置`r`这样所有的值都在`[pos, r]`至少是`cur_max / 2`考虑更新后。 我们不进行扫描，而是进行二分搜索`r`使用范围最小/最大查询来检查可行性。 

可行性检查确保在`[pos, r]`，没有元素违反相对于当前最大值的条件。 我们尽可能地扩展，因为任何有效段在遇到违规元素之前都必须是最大的。 
4. 移动`pos`到`r + 1`，并更新`answer += (r - pos + 1)`因此。 
5.消费完一个segment后，更新`cur_max`具有该段中的最大值。 这反映了这样一个事实：当我们延长步行时间时，跑步最大值只会增加。 
6. 如果在任何时候都无法取得进展或者超出了双倍边界，请停止。 如果我们完成至少一个完整周期而没有遇到违规，则返回 -1，因为该过程将无限期地继续下去。 

正确性取决于这样的事实：步行可以分解为阈值保持稳定的最大有效段。 每个段恰好在某个值违反当前最大值下的条件时结束，此时下一个段以可能更大的最大值开始。 

### 为什么它有效

 不变量是在每个段的开始处，`cur_max`等于迄今为止看到的所有值的最大值，并且当前段内的每个元素都满足相对于该最大值的条件。 由于阈值相对于单调`cur_max`，任何违规都必须发生在元素降至当前最大值一半以下的最早位置。 通过始终跳转到最大有效扩展，我们永远不会跳过潜在的停止点，也永远不会过早地切断有效段。 这保证了模拟与原始的逐步过程相匹配，但采用压缩形式。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        n = len(arr)
        self.n = 1
        while self.n < n:
            self.n *= 2
        self.seg = [0] * (2 * self.n)
        for i in range(n):
            self.seg[self.n + i] = arr[i]
        for i in range(self.n - 1, 0, -1):
            self.seg[i] = max(self.seg[2 * i], self.seg[2 * i + 1])

    def query(self, l, r):
        if l > r:
            return 0
        l += self.n
        r += self.n
        res = 0
        while l <= r:
            if l % 2 == 1:
                res = max(res, self.seg[l])
                l += 1
            if r % 2 == 0:
                res = max(res, self.seg[r])
                r -= 1
            l //= 2
            r //= 2
        return res

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = a + a

    st = SegTree(b)

    ans = []

    for i in range(n):
        pos = i
        end = i + n - 1
        cur_max = 0
        cnt = 0

        while pos <= end:
            lo, hi = pos, end
            best = pos

            while lo <= hi:
                mid = (lo + hi) // 2
                mx = st.query(pos, mid)
                if mx >= cur_max / 2:
                    best = mid
                    lo = mid + 1
                else:
                    hi = mid - 1

            if best < pos:
                break

            seg_max = st.query(pos, best)
            cnt += best - pos + 1
            cur_max = max(cur_max, seg_max)
            pos = best + 1

        if pos > end:
            ans.append(-1)
        else:
            ans.append(cnt)

    print(*ans)

if __name__ == "__main__":
    solve()
```该实现在双倍数组上构建线段树，以便每个范围最大查询都是对数的。 然后，每个起始索引使用二分搜索执行贪婪分段，以在条件中断之前找到最远的可到达点。 这`cur_max`变量跟踪遍历过程中不断变化的最大值。 

一个微妙的细节是使用双倍数组而不是模运算。 这避免了重复的模运算，并使段查询在索引上纯粹线性。 另一个重要的一点是，在扩展之前会根据当前最大值检查停止条件，以确保我们永远不会在段内包含违规元素。

 ## 边缘情况

 一种重要的边缘情况是所有值都相等。 从任意位置开始，最大值立即等于该值，并且后续元素都不会严格小于一半，因此遍历永远不会终止。 该算法通过永远不会找到违规段并耗尽完整的双倍间隔来处理此问题，返回 -1。 

另一种边缘情况是当一个非常大的值出现在几个小值之后时。 在这种情况下，运行最大值会延迟，这会暂时收紧阈值。 基于分段的模拟正确地捕获了这一点，因为最大值仅在完成每个有效分段后才会更新，确保我们不会错误地假设跨越跳跃的稳定阈值。 

最后的边缘情况是起点本身是全局最大值。 在这种情况下，阈值立即变高，并且第一个违规元素可能会出现在一个或两个步骤内。 对段的二分搜索确保我们精确地检测到第一个无效位置，而不是超出它。
