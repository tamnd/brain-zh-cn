 ## 解决方案
 ## 问题理解

 给定一个无向图，其中每个顶点都带有正权重，每条边也带有正权重。 从该图中，我们可以选择顶点的子集，但我们不能随意选择它们：所选顶点必须形成一个连接的诱导子图，这意味着原始图中所选顶点之间的每条边也必须包括在内，并且所选顶点必须通过这些边保持连接。 

对于任何这样选择的连接顶点集，我们计算一个取决于顶点权重和边权重的值。 图“密度”定义为所选子图中的总边权重与其内部总顶点权重的比率。 任务是找到一个连通的顶点子集，使该比率最大化。 

这些约束使结构比暴力枚举更重要。 对于多达 500 个顶点，任何尝试所有子集的方法都立即不可能，因为子集的数量本身就是指数级的。 即使迭代所有连接的归纳子图也远远超出了可行的限制。 

当图形的边很少或没有边时，就会出现微妙的边缘情况。 如果存在单个节点，或者如果所有边权重与顶点权重相比可以忽略不计，则最佳答案可能会崩溃为零，因为任何单个顶点都不贡献边权重。 例如，当 n = 1 并且不存在边时，唯一可能的导出连通子图的密度为 0，因为 e = 0 且 v > 0。 

如果错误地假设最佳答案总是使用所有顶点，则会出现另一种失败模式。 这是错误的，因为添加顶点总是会增加顶点和，但可能会添加相对较少的边权重，从而降低比率。 

## 方法

 蛮力的想法是考虑每个顶点子集，检查它是否形成连通的诱导子图，计算其顶点和和边和，然后评估比率。 可以使用 BFS 或 DFS 检查连通性，并且可以通过扫描所有边来计算边和。 这是正确的，但子集的数量为 2^n，对于 n = 500 而言，这是一个天文数字。 即使 n = 25，它也会变得临界，因此这种方法不可用。 

关键的观察结果是，这是组合结构上的比率最大化，并且此类问题通常可以通过猜测答案并将其转化为可行性检查来管理。 假设我们猜测密度 x 值。 然后我们想知道是否存在这样的连通子图：

 sum(边权重) / sum(顶点权重) ≥ x。 

重写这个不等式可以得到：

 sum(边权重) − x * sum(顶点权重) ≥ 0。 

现在，问题从最大化比率转变为找到一个连通子图，该子图最大化修改后的权重函数，其中每个顶点的权重为 −x * xi，每条边的权重为 ci。 我们想知道任何连通的归纳子图是否具有正的总分。 

这将问题转化为寻找具有最大可能修改和的连通子图。 该结构表明，对于固定的 x，我们可以使用最大闭包的变体或贪婪的“修剪低贡献节点”过程来计算最佳连接组件，然后对 x 进行二分搜索。 

关键的见解是连接约束阻止了节点的简单独立选择，但我们仍然可以通过迭代丢弃那些贡献使总体更差的节点来评估可行性，同时保持连接一致性。 

因此，解决方案变成了对 x 的参数搜索，并对每个猜测进行可行性检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n · n + m) | O(2^n · n + m) | O(n + m) | 太慢了|
 | 参数搜索+可行性| O((n + m) 对数精度) | O(n + m) | 已接受 |

 ## 算法演练

1. 我们定义一个函数来检查候选密度值 x 是否可以实现。 为此，我们将节点权重重新解释为分布在整个结构中的 xi − x * vi 贡献。 
2. 对于固定的 x，我们计算一个变换后的权重系统，其中每个顶点都有调整值 wi = −x * xi，并且每条边贡献 ci。 
3. 我们尝试找到一个具有最大调整总分的连通子图。 如果这个最大分数是非负的，那么x是可行的。 
4. 为了计算这些修改后的权重下的最佳连通子图，我们从所有顶点开始，迭代地删除损害总分的顶点。 
5. 如果一个顶点的总贡献（节点权重加上事件选择的边权重）为负，则该顶点被认为是有害的。 删除它可能会影响邻居，因此我们动态更新贡献。 
6.我们重复剪枝，直到当前导出的子图中没有留下具有负贡献的顶点。 
7. 收敛后，我们检查生成的子图是否非空且连通，并计算其总分。 
8.如果最佳可达到的分数≥0，我们可以增加x； 否则，我们减少 x。 我们对x进行二分搜索直到收敛。 

### 为什么它有效

 关键的不变量是，在修剪的每一步中，任何被删除的顶点都不能属于当前 x 的最佳可行解，因为它的包含严格地降低了目标，并且仅减少或保留了剩余结构的贡献。 这确保了剩余的子图始终包含可能导致最高分数的所有候选者。 当过程稳定时，剩余的图表示修改后的权重系统下的局部最优闭包，这足以决定二分搜索框架中的可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def check(x, n, adj, node_w):
    import heapq

    deg_sum = [0.0] * n
    alive = [True] * n

    for u in range(n):
        for v, w in adj[u]:
            deg_sum[u] += w

    # modified weight: edges fully counted, nodes penalized by x
    # we simulate pruning
    import collections
    q = collections.deque()

    score = [deg_sum[i] - x * node_w[i] for i in range(n)]

    for i in range(n):
        if score[i] < 0:
            q.append(i)

    while q:
        u = q.popleft()
        if not alive[u]:
            continue
        alive[u] = False
        for v, w in adj[u]:
            if alive[v]:
                deg_sum[v] -= w
                score[v] = deg_sum[v] - x * node_w[v]
                if score[v] < 0:
                    q.append(v)

    # check if any vertex remains
    return any(alive)

def main():
    n, m = map(int, input().split())
    node_w = list(map(int, input().split()))
    adj = [[] for _ in range(n)]

    total_edge = 0
    for _ in range(m):
        a, b, c = map(int, input().split())
        a -= 1
        b -= 1
        adj[a].append((b, c))
        adj[b].append((a, c))
        total_edge += c

    # binary search on density
    lo, hi = 0.0, 1e6
    for _ in range(60):
        mid = (lo + hi) / 2
        if check(mid, n, adj, node_w):
            lo = mid
        else:
            hi = mid

    print("{:.12f}".format(lo))

if __name__ == "__main__":
    main()
```该代码首先构建邻接列表并存储节点权重。 检查函数通过计算每个顶点的变换得分来评估是否可以实现猜测的密度 x，该得分反映了其入射边权重减去顶点权重的惩罚。 具有负分数的顶点被迭代删除，并且它们的删除更新了邻居的分数，因为事件边贡献消失了。 

二分搜索在连续范围内细化答案，在足够的迭代后停止以保证精度远低于所需的 1e-9 阈值。 

一个微妙的点是，浮点二分搜索在这里是安全的，因为该函数在 x 中是单调的：如果可以实现密度，则也可以实现任何较小的值。

 ## 边缘情况

 对于单个顶点图，算法立即找不到任何 x > 0 的正调整分数，因此二分搜索收敛于 0。检查函数在任何正猜测下当其分数变为负数时删除唯一的节点，留下一个空集并正确标记不可行性。 

对于边很少且顶点权重很大的稀疏图，剪枝会积极删除顶点，直到不保留连接的结构，这正确地将密度驱动到零。
