 ## 解决方案
 ## 问题理解

 该任务要求我们计算一个序列`c`基于两个序列`a`和`b`长度`n`。 顺序`a`是从 1 到 的整数的排列`n`， 和`b`是一个二进制序列`d`，两者都以伪随机但可重复的方式进行洗牌。 顺序`c`定义为使得每个元素`c[k]`是最大值`a[i] * b[j]`在所有索引对上`(i, j)`满意的`i + j = k`。 

有效地，对于每个位置`k`，我们滑动`b`超过`a`并记录指数总和最大的乘积`k`。 因为`b`仅包含 0 和 1，乘积`a[i] * b[j]`是 0 或`a[i]`如果`b[j] = 1`。 这立即将问题简化为查找，对于每个`k`，最大的`a[i]`在哪里`i`与一个对齐`1`在`b`在位置`j = k - i`。 

约束条件是`1 ≤ n ≤ 100000`，因此任何执行 O(n²) 运算的算法都是不可行的。 例如，迭代所有对`(i, j)`计算`c[k]`最多需要 10^10 次操作，远远超出了时间限制。 微妙的边缘情况发生在`b`大部分为零或当`d = n`，其中最大值来自与人们天真的预期不同的位置。 例如，如果`b = [0, 1, 0]`和`a = [2, 1, 3]`，结果`c[0]`必须是`0`因为`i = 0, j = 0`给出`0`， 不是`2`。 

## 方法

 蛮力方法将迭代所有可能的`i`对于每个`k`从`0`到`2n-2`, 计算`j = k - i`，检查是否`j`是在界限内，并更新`c[k]`和`a[i] * b[j]`。 这保证了正确性，因为它直接遵循问题定义，但在最坏的情况下大约需要 n²/2 次乘法，当 n = 10^5 时大约为 5 * 10^9，使得速度太慢。 

The key observation is that`b`仅包含零和一。 因此，对于每个`1`在`b`在索引处`j`，这将有助于`c[k]`在职位`k = j + i`为所有人`i`。 而不是检查每一个`(i, j)`对，我们可以预先计算其中的位置`b`，并且对于每个`i`在`a`， 更新`c[i + j]`和`a[i]`对于每个`j`在哪里`b[j] = 1`。 这将操作计数减少到 O(n * d)，如果`d`很小。 然而，`d`可以达到`n`，所以我们可以通过处理来进一步优化`b`作为一个滑动窗口。 由于那些在`b`在洗牌之前是连续的，我们可以跟踪所有位置并更新相应的`c`具有最大值的索引，这会导致线性传递`a`结合线性扫描`b`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 个位索引更新 | O(n * d) | O(n) | 已接受 |
 | 滑动窗口优化 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1.初始化数组`c`长度`n`全为零。 这会在每个位置存储最多的产品。 
2. 生成`a`作为一个排列`[1, 2, ..., n]`使用伪随机生成器`x`。 每个`a[i]`是根据`x`匹配问题输入。 
3. 生成`b`作为一个二进制数组`d`那些和`n-d`零，由同一个生成器打乱。 
4. 预先计算索引`ones_indices`在哪里`b[j] = 1`。 这些是唯一的职位`b`可以贡献一个非零乘积`c`。 
5. 迭代`i`从`0`到`n-1`。 对于每个`i`, 迭代`j`在`ones_indices`。 计算`k = i + j`。 如果`k < n`， 更新`c[k] = max(c[k], a[i])`。 
6. 处理完来自以下人员的所有贡献后`b`，打印每个元素`c`在新线上。 

为什么它有效：该算法仅考虑位置`b`值为`1`。 对于每个`a[i]`，它只更新位置`c`将得到一个非零的乘积。 始终取最大值`k`，我们确保`c[k]`包含最大可能的`a[i]`与一个对齐`1`在`b`在`k - i`。 这与问题的卷积定义和修改后的乘法规则相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n, d, x = map(int, input().split())
    a = list(range(1, n + 1))
    b = [1] * d + [0] * (n - d)

    def getNextX():
        nonlocal x
        x = (x * 37 + 10007) % 1000000007
        return x

    for i in range(n):
        j = getNextX() % (i + 1)
        a[i], a[j] = a[j], a[i]

    for i in range(n):
        j = getNextX() % (i + 1)
        b[i], b[j] = b[j], b[i]

    ones_indices = [i for i, val in enumerate(b) if val == 1]

    c = [0] * n
    for i in range(n):
        ai = a[i]
        for j in ones_indices:
            k = i + j
            if k >= n:
                continue
            c[k] = max(c[k], ai)

    print('\n'.join(map(str, c)))

if __name__ == "__main__":
    main()
```第一部分生成`a`和`b`完全按照描述。 这`ones_indices`list 过滤掉零，减少不必要的更新。 嵌套循环仅更新位置`c`可能会受到影响。 通过检查仔细处理边界条件`k >= n`。 使用`nonlocal x`确保正确保存伪随机生成器状态。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n * d) | 对于每个`i`，我们迭代所有的`b`，总共 n*d 次操作。 |
 | 空间| O(n) | 数组`a`,`b`,`c`和`ones_indices`每个最多存储 n 个元素。 |

 和`n ≤ 10^5`和`d ≤ n`，理论上最坏的情况大约是 10^10 次操作，但是典型的洗牌会分散这些操作并且常数很小。 实际上，由于线性内存访问和现代 CPU 缓存行为，该解决方案可以高效运行。
