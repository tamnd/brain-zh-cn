 ## 解决方案
 ## 问题理解

 我们有一组城市，每个城市都有一个代表人口的非负权重。 最初，任何城市之间都没有联系。 目标是确定是否可以逐渐添加边缘，以便最终所有城市都成为单个连接组件的一部分。 

不同的是，两个城市之间并不总是允许存在边缘。 我们是否可以连接两个城市取决于一个条件，该条件涉及包含至少一个端点的连接组件中的人口总和。 如果我们尝试连接城市 i 和 j，我们会查看当前处于其连接组件联合体中的所有城市，对其人口进行求和，并要求该总数至少为 i·j·c。 

关键的困难在于这个条件动态地取决于组件如何合并。 每条成功的边都会增加未来合并的可用总和，因此该过程是自适应的而不是静态的。 

输入规模很大：所有测试用例最多有 2 · 10^5 个城市。 这排除了任何重复模拟所有可能的边缘或从头开始重新计算连接的方法。 每个测试用例接近 O(n^2) 的情况都是立即不可行的，因为即使是 n = 2 · 10^5 的单个测试也需要大约 4 · 10^10 检查。 

一种天真的解释表明，我们可以模拟一个不断增长的图并重复尝试所有可能的边，但这会失败，因为每个步骤都涉及重新计算组件的总和。 

一个更微妙的问题是约束取决于乘积 i·j。 这会产生强大的排序压力：涉及大索引的边比涉及小索引的边更难形成。 连接任意有效对的粗心贪婪策略可能会失败，因为它可能会“浪费”昂贵连接上的早期合并并阻止其他地方必要的增长。 

例如，如果高索引节点合并得太早，它们需要大量尚不可用的资金，这可能会阻止未来的连接，即使不同的顺序会成功。 

## 方法

 暴力方法会重复维护连接的组件，并尝试每对可能的节点 i 和 j，检查它们的组件是否可以在当前总和条件下合并。 每次成功的合并都会更新联合结构和组件总和。 然而，有 O(n^2) 种可能的边，并且每次检查都涉及组件查询，使得这种方法太慢。 

关键的观察是我们实际上从来不需要任意边缘。 约束 i·j·c 仅取决于索引，而不取决于当前结构。 由于 i 和 j 是固定的，我们可以认为每个节点都有一个取决于其索引的“连接成本”，而组件仅通过 a_i 的总和提供累积“预算”。 

问题变成了一个受控的合并过程：我们希望以一种不断解锁更多可行合并的方式来增长组件。 一个重要的见解是，如果我们决定扩展一个组件以包含一个新节点，我们应该总是首先合并最便宜的可用节点，因为尽早增加总和会使所有未来的约束变得更容易。 

这导致了基于排序的贪婪想法。 由于约束随着 i · j 的增长而增长，因此较小的索引总是更容易连接。 我们希望从最小的索引开始逐步构建一个不断增长的组件，并确保在每一步中，累积的金额足以“支付”连接下一个节点的费用。

我们不再考虑任意边，而是将这个过程重新解释为维护一个不断增长的类似前缀的组件：我们反复尝试附加当前总和下可以提供的最小剩余节点。 如果在某个时候我们无法附加下一个所需的节点，那么任何替代排序都不会成功，因为任何其他选择只会增加未来合并的成本。 

因此，我们将问题简化为按递增索引顺序重复选择下一个节点并检查当前累加和是否满足连接要求。

 | --- | --- | --- | --- |
 | 蛮力（模拟所有边缘）| O(n^2 log n) | O(n^2 log n) | O(n) | 太慢了 |
 | 贪婪有序构造 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.按索引对节点进行排序，但由于索引已经是1到n，所以我们直接按升序处理。 这反映出小指数的约束较弱，应首先纳入。 
2. 维护当前连接组件的总体总和的运行总计。 最初，我们从最小的节点开始，所以总和是a₁。 
3. 迭代从 2 到 n 的节点，并尝试将节点 i 连接到现有组件。 
4. 为了连接节点 i，我们检查当前分量和是否足够大以满足连接 i 的最差要求条件。 由于涉及 i 的任何连接最终都必须满足组件中已有的某些 j 的 i·j·c 的要求，因此最具限制性的情况来自于连接到组件中的最小索引，在最佳构造顺序中该索引始终为 1。 因此，我们检查当前总和是否至少为 i·c。 
5. 如果条件成立，我们通过将 a_i 添加到总和中，将节点 i 合并到组件中。 否则，我们立即得出结论：连接是不可能的。 
6. 如果所有节点都成功合并，我们输出YES。 

### 为什么它有效

 该过程依赖于这样一个事实：在任何成功的构造中，添加节点 i 的瓶颈是其最早可能的连接，该连接始终是到增长组件内已经具有最小索引的节点。 任何延迟添加 i 的替代策略只会增加未来所需的产品，而不会提高可行性。 这创造了一个单调增长的条件：一旦在最好的情况下总和不足以满足 i 的需要，未来合并的重新安排就无法修复它，因为所有未来的节点只会增加索引，从而增加需求。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, c = map(int, input().split())
    a = list(map(int, input().split()))

    s = a[0]
    ok = True

    for i in range(1, n):
        if s < (i + 1) * c:
            ok = False
            break
        s += a[i]

    print("Yes" if ok else "No")
```实现直接遵循贪心构造。 我们维护一个代表当前连接组件的运行总和。 在每一步中，我们都会测试在最小可能连接要求下添加下一个节点是否可行。 使用的索引是 i + 1，因为数组在代码中是从 0 开始的，但在问题中是从 1 开始的。 

唯一的微妙之处是意识到我们永远不需要显式地模拟边缘。 仅总和就足够了，因为假设我们以递增的索引顺序顺序连接，则始终可以保持连接性。

 ## 边缘情况

 一个关键的边缘情况是早期节点的值极小或为零。 即使后面的节点包含非常大的群体，如果第一步不能满足初始阈值，算法也会立即失败。 例如，使用输入`n=3, c=5, a=[0,0,100]`，该过程在第一次转换时停止，因为所需的值取决于索引 2，而不是未来的累积。 

当值很大但 c 也很大时，会出现另一种微妙的情况。 即使是统一的大数组也可能会失败，因为约束随索引线性增长。 例如，`a=[10^12,10^12,10^12]`和`c=10^6`在 i=2 时失败，因为要求变为 2·10^6，很快超出了后续步骤中部分和可以支持的范围。 

这些案例证实该算法严格的顺序可行性检查正确捕获了所有不可逆的故障。
