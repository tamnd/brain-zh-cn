 ## 解决方案
 ## 问题理解

 我们得到了一个概念乘法表`n`行和`m`列。 排中`i`和列`j`，存储的值很简单`i × j`。 如果我们把所有的都压平`n × m`将值放入一个列表中并按非降序对它们进行排序，我们被要求找到出现在列表中的值`k`第-个位置。 

因此，任务不是显式构建表，而是了解产品的分布`i × j`并回答对该多重集的排名查询。 

约束很大：两个维度都可以达到`5 · 10^5`，这使得表的大小可能`2.5 · 10^11`。 任何试图直接枚举条目的方法都是立即不可能的，甚至存储结构也是不可能的。 这迫使我们采取一种解决方案，我们从不具体化网格，而是计算它的属性。 

天真的解释可能会尝试生成所有产品并对它们进行排序，但即使生成单行也会产生成本`O(m)`对所有行执行此操作会导致`O(nm)`的操作，这远远超出了可行的范围。 

当许多产品（尤其是少量产品）相同时，就会出现微妙的边缘情况。 例如，在一个`3 × 3`表，值`2`只出现两次，而`4`出现三次，来自不同的配对。 任何假设产品独特性的方法都会失败。 

另一个问题是溢出思维：乘积适合 32 位整数，但要计算有多少个值`≤ x`可以达到`n × m`，这需要 64 位算术。 

## 方法

 蛮力方法很简单：计算每个值`i × j`，将它们存储在数组中，排序，然后选择`k`-th 元素。 这是正确的，因为它直接构造了问题中描述的多重集。 然而，它需要生成`n × m`值，在最坏的情况下约为`2.5 · 10^11`相同数量元素的乘法和内存。 即使忽略记忆，仅凭时间就不可能做到这一点。 

关键的结构观察是我们不需要知道所有值，只需要知道有多少个值小于或等于候选数`x`。 如果我们可以有效地计算这个计数，那么我们就可以二分搜索答案。 这样做的原因是单调性：如果一个值`x`足够大至少是`k`-th 最小的元素，则任何较大的值也有效，任何较小的值则无效。 这创建了一个适合二分搜索的单调谓词。 

所以问题归结为计数，对于一个固定的`x`, 有多少对`(i, j)`满足`i × j ≤ x`。 对于每一行`i`， 有效的`j`值来自`1`最多`min(m, x // i)`。 对所有行求和即可得到总计数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nm log(nm)) 由于排序 | O(纳米) | 太慢了|
 | 二分查找+计数| O(n log(最大值)) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.我们寻找最小值`x`这样至少`k`表中的数字是`≤ x`。 这将排名问题重新构建为决策问题。 
2. 我们设置二分搜索范围为`1`到`n × m`，因为最小值是`1 × 1`最大的是`n × m`。 
3. For a candidate value`mid`，我们计算有多少产品`i × j`是`≤ mid`。 对于每一行`i`，我们将有效列计算为`min(m, mid // i)`。 这是有效的，因为在行中`i`，值线性增长为`i, 2i, 3i, ...`。 
4. 我们将这些计数相加`i`从`1`到`n`。 如果总数至少为`k`， 然后`mid`足够大，所以我们将搜索向左移动。 否则，我们向右移动。 
5、二分查找收敛后，答案是最小的`mid`即满足条件。 

### 为什么它有效

 核心不变量是函数`F(x)`定义为“表条目数 ≤ x” 是非递减的`x`。 一旦有一个值`x`产生计数 ≥`k`，每个较大的值也会产生计数 ≥`k`。 这种单调结构保证二分搜索收敛到最小有效值，这正是`k`- 排序多重集中的第最小元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m, k = map(int, input().split())

def count_le(x):
    total = 0
    for i in range(1, n + 1):
        total += min(m, x // i)
    return total

lo, hi = 1, n * m

while lo < hi:
    mid = (lo + hi) // 2
    if count_le(mid) >= k:
        hi = mid
    else:
        lo = mid + 1

print(lo)
```功能`count_le`是关键的组成部分。 对于每行索引`i`,`x // i`告诉我们在超过之前我们可以在该行走多远`x`。 我们把它夹在`m`因为每一行只有`m`列。 

二分搜索是在值域上完成的，而不是在索引上完成的。 这种区别很重要，因为数组不是显式构造的。

 ## 边缘情况

 像一个小网格`1 × m`行为就像一个简单的序列`1, 2, ..., m`。 该算法正确归约，因为每一行最多贡献一个元素，并且`min(m, x // i)`变成`min(m, x)`什么时候`i = 1`。 

什么时候`k = n × m`，答案一定是最大乘积`n × m`。 在二分搜索期间，只有低于此最大值的值才会使谓词失败，因此搜索正确地收敛于上限。 

当许多产品重复时，例如多种形成方式`6`在一个`3 × 3`网格，计数功能正确地包括所有出现的情况，因为每个有效的`(i, j)`对通过独立计数`min(m, x // i)`。
