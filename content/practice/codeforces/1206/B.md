 ## 解决方案
 ## 问题理解

 我们得到一个整数数组。 在一次操作中，我们可以选择任何元素，然后将其增加 1 或减少 1。每次更改都会花费一枚硬币。 

目标是修改数组，使所有元素的乘积恰好为 1，同时花费尽可能少的硬币。 

由于最终乘积必须为 1，因此最终数组中的每个元素都必须为 1 或 -1。 任何绝对值大于 1 的值都会带来不必要的成本，因为进一步接近 ±1 总是会减少所需的操作数量。 零也不能保持为零，因为任何包含零的乘积都是零。 

约束条件$n \le 10^5$立即表明我们需要一个线性或近线性的解决方案。 任何尝试多种可能的最终配置或对产品执行动态编程的方法都将过于昂贵。 拥有 100,000 个元素，$O(n)$扫描是理想的。 

一些边缘情况值得关注。 

考虑一个仅包含零的数组：```
1
0
```答案是1。我们可以通过一次操作将0变成1。 仅计算负数和正数的解决方案可能会忘记处理零。 

考虑奇数个负数，没有可用的零：```
3
-1 -1 -1
```产品为-1。 为了使乘积等于 1，必须将一个元素从 -1 更改为 1，这需要 2 次操作。 正确答案是 2。粗心的贪婪解决方案可能会在将所有内容转换为最接近的 ±1 后停止并错误地返回 0。 

现在考虑至少有一个零的奇数个负数：```
2
-1 0
```最便宜的选择是将 0 转换为 -1，成本为 1，得到产品 1。答案是 1。自动将每个 0 转换为 1 的解决方案将花费 3 次操作。 

## 方法

 蛮力观点是考虑每个元素的最终值并尝试所有可能的 1 和 -1 赋值。 由于每个元素有两种可能的最终状态，因此有$2^n$可能的目标数组。 对于每个任务，我们可以计算成本并检查乘积是否等于 1。 

这在概念上是有效的，因为每个有效的最终数组仅由 1 和 -1 组成。 问题在于搜索空间的大小。 和$n=10^5$， 甚至$2^{50}$可能性已经是不可能的了，更不用说$2^{100000}$。 

关键的观察结果是，在计算达到 1 或 -1 的最便宜方法时，每个元素都可以独立处理。 

对于正数$x>0$，最便宜的贡献就是把它变成1，成本$x-1$。 

对于负数$x<0$，最便宜的贡献是将其变成-1，成本$-1-x$。 

对于 0，达到 1 或 -1 的成本正好为 1。 

在使每个元素尽可能接近其自然目标之后，唯一剩下的问题是负值数量的奇偶性。 当且仅当 -1 值的数量为偶数时，乘积才等于 1。 

如果负数的数量已经是偶数，我们就完成了。 

如果很奇怪，我们还需要再调整一次。 当存在零时，我们可以简单地将一个零转换为 -1 而不是 1，除了通常的 1 个硬币之外，无需额外成本。 如果没有零，我们必须将最后一个 -1 更改为 1，这需要 2 次额外操作。 

这直接导致线性时间贪婪解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n \cdot n)$|$O(1)$| 太慢了 |
 | 最佳 |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 初始化三个变量：总成本、负元素数量和零数量。 
2. 扫描一次数组。 
3.如果当前值为正，则概念上将其转换为1。添加$x-1$到成本。 
4. 如果当前值为负，则概念上将其转换为-1。 添加$-1-x$到成本并增加负计数器。 
5. 如果当前值为零，则将成本加 1 并递增零计数器。 

零可以以相同的成本变成 1 或 -1，所以现在我们只记录它的存在。 
6.处理完所有元素后，检查负数的个数是否为偶数。 
7. 如果底片的数量是偶数，则当前成本已经是最优的。 
8. 如果负数为奇数且至少存在一个零，则无需额外费用。 

一个零可以变成 -1 而不是 1，固定奇偶校验，同时仍然花费 1 个硬币。 
9. 如果负数为奇数且没有零，则答案加 2。 

唯一的选择是将最后一个 -1 更改为 1，这需要两次操作。 
10. 输出总成本。 

### 为什么它有效

 对于每个非零元素，最便宜的可达值$\{-1,1\}$是独立确定的。 任何替代选择的成本都会更高。 例如，将正数更改为 -1 的成本始终比将其更改为 1 的成本高 2。 

在这些局部最优选择之后，唯一的全局条件是 -1 值的总数必须是偶数。 如果奇偶性已经正确，则局部最优决策形成全局最优解。 

当奇偶校验错误时，最便宜的校正要么使用现有的零（它可以在没有额外成本的情况下变为 -1），要么支付恰好 2 个额外操作以将最终的 -1 翻转为 1。不存在更便宜的调整，因此算法始终产生最小成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    cost = 0
    negatives = 0
    zeros = 0

    for x in a:
        if x > 0:
            cost += x - 1
        elif x < 0:
            cost += -1 - x
            negatives += 1
        else:
            cost += 1
            zeros += 1

    if negatives % 2 == 1 and zeros == 0:
        cost += 2

    print(cost)

solve()
```第一个循环计算使每个元素达到最接近的有用值的最小成本。 正数向 1 移动，负数向 -1 移动，零需要一次操作才能离开零。 

变量`negatives`记录有多少个元素自然变成-1。 变量`zeros`记录我们是否有免费修复奇偶校验的灵活性。 

最终条件是唯一微妙的部分。 奇数个负数意味着乘积将为 -1。 如果没有可用的零，则 -1 必须变为 1，这恰好需要 2 次额外操作。 当至少存在一个零时，该零可以变为 -1 而不是 1，从而固定奇偶校验而不增加已计算的成本。 

Python 整数可以轻松处理答案大小，因为最大可能成本远低于$10^{14}$。

 ## 边缘情况

 ### 奇数个负数且没有零

 输入：```
3
-1 -1 -1
```扫描产生成本 0、负数 3、零 0。乘积将为 -1，因为负数的数量是奇数。 由于没有可用的零，该算法加 2 并返回 2。 

这是最便宜的修复方法，因为将 -1 更改为 1 正好需要两次操作。 

### 带零的负数的奇数

 输入：```
2
-1 0
```扫描产生成本 1、负数 1、零 1。负数为奇数，但存在零。 我们没有将零转换为 1，而是使用已计数的相同操作将其转换为 -1。 

最终的数组变成`[-1, -1]`，其乘积为 1。答案仍然是 1。 

### 全零

 输入：```
3
0 0 0
```每个零贡献 1，成本为 3。负数仍然为 0，这是偶数。 

该算法返回 3。一个有效的最终数组是`[1, 1, 1]`。 

### 单个负元素

 输入：```
1
-1
```扫描给出成本 0、负数 1、零 0。奇偶校验为奇数，因此算法加 2。 

最终答案是2，对应改变`-1`进入`1`。 

这种情况很容易被忽视，因为元素已经达到目标值之一，但产品要求仍然强制进行额外的调整。
