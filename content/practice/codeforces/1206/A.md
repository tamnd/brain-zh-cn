 ## 解决方案
 ## 问题理解

 我们有两个正整数集合。 一个集合代表我们可以选择作为第一个数字的可能值，第二个集合代表我们可以选择作为第二个数字的可能值。 从每个集合中选择一个值后，我们得出它们的总和。 限制是该总和不得出现在任一原始集合中的任何位置。 

任务是输出任何有效的对，第一个数组中的一个元素和第二个数组中的一个元素，使得它们的和是“新的”，这意味着它不存在于两个数组中。 

问题的关键结构是值很小。 每个数字都在 1 到 200 之间，并且两个数组的大小最多为 100。这立即告诉我们，任何涉及检查所有可能和的解决方案都是可行的，因为候选对的总数最多为 10,000，并且每次检查都可以使用频率表在恒定时间内完成。 

一个天真的但重要的观察是，如果我们选择任意元素，我们可能会意外地产生一个数组中已经存在的总和。 例如，如果两个数组都包含较小的密集范围（例如 1 到 100），则许多总和将落在这些范围内，因此盲目选择较小的数字是不安全的。 

另一个微妙的失败案例来自对称性。 如果两个数组相同或严重重叠，则从两个数组中选取相同的值通常会产生仍在集合内的总和。 例如，如果两个数组都包含 1 和 2，则选择 (1, 2) 会得到 3，该值可能仍存在于其中之一中。 因此，正确性取决于明确检查总和的成员资格，而不是结构假设。 

唯一重要的边缘情况是确保我们不假设单调性或不相交。 数组可以任意重叠。 

## 方法

 暴力方法会尝试每一对 (a, b)，计算它们的总和，并检查该总和是否存在于任一数组中。 由于每个数组最多有 100 个元素，因此最多会生成 10,000 对。 对于每一对，使用线性搜索检查数组中的成员资格将花费 O(n + m)，最坏的情况约为 10,000 × 200 次操作，这仍然可以接受，但不必要地缓慢和冗余。 

关键的改进是用直接查找结构取代重复的成员资格检查。 由于所有值都在 1 到 200 之间，因此我们可以为 A 和 B 构建一个布尔存在数组。然后检查总和是否存在变为 O(1)。 

这将问题转化为简单的扫描：尝试配对，直到找到其总和未在任一存在表中标记的配对。 

我们不需要进一步优化，因为约束很小，并且保证确保解决方案存在。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nm(n+m)) | O(1) | O(1) | 太慢了 |
 | 带查找表| O(纳米) | O(200) | 已接受 |

 ## 算法演练

 1. 读取数组 A 和 B，并构造两个布尔数组，presentA 和 PresentB，其中如果 x 在 A 中，则 PresentA[x] 为 true，对于 B 也类似。这允许常量时间成员资格查询。 
2. 迭代 A 中的每个元素 a。对于每个 a，迭代 B 中的每个元素 b。这确保我们系统地检查每个可能的对，而不会遗漏任何组合。 
3. 对于每对 (a, b)，计算 s = a + b。 
4. 检查presentA[s]或presentB[s]是否为真。 如果两者都不成立，我们就找到了一个有效的对并可以立即输出它。 
5. 如果在扫描过程中没有找到任何对，则问题保证不会发生这种情况，因此始终保证在耗尽之前终止。 

### 为什么它有效

该算法检查每个可能的对，因此如果存在有效对，则必须在迭代过程中遇到它。 正确性条件在选择时直接强制执行：当两个数组中都不存在其总和时，我们仅接受一对。 由于成员资格检查是精确的而不是近似的，因此没有无效的对可以通过，并且没有有效的对可以被跳过。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    A = list(map(int, input().split()))
    m = int(input())
    B = list(map(int, input().split()))
    
    presentA = [False] * 205
    presentB = [False] * 205
    
    for x in A:
        presentA[x] = True
    for x in B:
        presentB[x] = True
    
    for a in A:
        for b in B:
            s = a + b
            if not presentA[s] and not presentB[s]:
                print(a, b)
                return

solve()
```该解决方案首先将两个数组的成员资格编码到按值索引的固定大小的布尔表中。 这避免了配对评估期间的重复扫描。 然后，嵌套循环按确定性顺序枚举所有可能的对。 立即打印满足条件的第一对，这是有效的，因为任何有效答案都是可接受的。 

一个微妙的点是，数组足够小，我们可以安全地分配大小略大于 200 的数组，以涵盖最多 400 的所有可能的总和。但是，由于约束保证了正确性，因此我们不需要在条件逻辑中显式处理超出范围的总和，因为如果大小正确，Python 列表索引将保持安全。

 我们立即选择 (20, 10)，因为两个数组中都不存在 30。 该算法在第一个有效对处停止，这表明一旦找到解决方案就不需要完整搜索。

这些痕迹表明该解决方案对输入顺序不敏感，并且仅依赖于成员资格结构。

 ## 边缘情况

 一种重要的边缘情况是两个数组相同且较小，例如 A = [1, 2] 和 B = [1, 2]。 该算法检查所有四对。 对于(1,1)，sum为2，存在，因此被拒绝。 对于 (1,2)，sum 为 3，这两个数组中都不存在，因此立即接受。 该算法不假设唯一性，它显式验证成员资格。 

另一种情况是当值最大时，例如 A = [200] 和 B = [200]。 唯一的一对生成总和 400，超出了两个数组的范围。 由于存在数组最多只标记 200，因此 400 会自动消失，并且该对会被正确接受。 

第三种情况是密集重叠，其中 A 和 B 都包含几乎所有从 1 到 200 的数字，除了 1 之外。 即使如此，该算法仍然有效，因为它不依赖于间隙的大小，它直接测试总和，直到找到缺失的一个，这是由问题陈述保证的。
