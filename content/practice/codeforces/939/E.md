 ## 解决方案
 ## 问题理解

 我们正在维护越来越多的正整数集合。 集合开始为空，我们处理两种类型的操作：插入一个新数字，或者询问有关当前集合的问题。 

插入规则很特殊：保证每个新数字至少与所有先前插入的数字一样大。 这意味着多重集有效地以非递减到达顺序维护。 

该查询要求我们选择当前数字的非空子集。 对于该子集，我们计算一个值，定义为其最大元素与其平均值之间的差。 我们必须返回该表达式在所有子集选择上的最大可能值。 

关键的困难在于我们没有针对每个查询独立地优化子集。 每次插入都会永久改变结构，并且查询可以出现在流中的任何位置。 由于操作多达 500,000 次，每个查询都无法从头开始重新计算。 

这些约束意味着任何在插入元素数量上具有二次行为的解决方案都将失败。 甚至$O(n)$每个查询导致$O(n^2)$最坏情况下的总工作量远远超出了限制。 我们被迫走向一种结构，其中每个插入都是$O(1)$或者$O(\log n)$，并且每个查询也是$O(1)$或者$O(\log n)$。 

子集优化产生了一个微妙的问题：天真的直觉可能建议仅尝试后缀或仅尝试包含最大元素的子集，但如果不仔细推理，很容易错过正确的约简。 另一个陷阱是假设我们必须显式跟踪每个查询的所有元素，这将导致重复扫描和超时。 

## 方法

 暴力方法将在每次查询时枚举当前集合的所有子集，计算它们的最大值和平均值，并跟踪最佳值。 即使限制于包含全局最大值的子集，我们仍然面临指数数量的选择。 这立即是不可行的。 

更合理的天真的方法是观察对于固定的最大元素，添加较小的元素会降低平均值。 因此，人们可能会尝试：固定最大元素，并考虑添加最小元素以增加最大值和平均值之间的差距。 然而，尝试剩余元素的所有组合仍然会导致指数行为。 

关键的结构观察来自于重写目标。 对于一个子集$s$，令其最大值为$M$，其大小为$k$，其总和为$S$。 其值为$$M - \frac{S}{k}.$$如果我们修复$M$，那么只有元素$\le M$符合条件，我们希望最小化平均值，相当于最大化选择值较小的元素的比率效应。 

由于元素按非递减顺序到达，因此当出现新的最大值时，所有先前的元素都已固定且已知。 这使我们能够将每个新值视为潜在的“锚定最大值”，并维护所有先前值的汇总统计数据。 

对于固定的最大值$a_i$，假设我们选择一个由该元素和早期元素的一些前缀组成的子集。 由于所有早期元素都较小或相等，因此最好的策略是包含所有元素或不包含它们，具体取决于它们是否改善目标。 这减少了维护前缀和和测试每个查询的线性表达式的问题。 

该表达式简化为对每个可能的分割点计算以下形式的值：$$a_i - \frac{S_j + a_i}{j+1}.$$重新排列给出了一种形式，我们可以使用凸包状或单调结构来维护候选值。 然而，由于非递减插入约束，一个更简单的观察成立：最优子集总是对应于序列的某个前缀加上当前最大值。 

因此，我们只需要维护插入元素的前缀和并有效地评估最佳分割。 每个查询都简化为检查单调序列上的预先计算的表达式，这可以增量维护。

 ## 算法演练

 1. 按顺序维护插入值的列表，以及运行的前缀和数组。 这允许对任何前缀的总和进行恒定时间计算。 
2. 对于每次插入，附加新值并更新前缀和。 由于值是不递减的，因此我们永远不需要重新排序或合并元素。 
3. 对于查询，使用维护的结构而不是显式循环隐式迭代可能的前缀长度。 我们跟踪从每个前缀派生的表达式的最佳值。 
4. 维护一个存储候选值的辅助结构：$$f(k) = k \cdot a_k - S_k$$或等效的转换表达式，允许快速评估以当前最大值结束的最佳子集。 
5. 在每个查询中，使用当前最大元素和存储的最佳候选元素计算最佳值，然后输出结果。 

核心思想是插入仅扩展域，并且由于元素是按到达排序的，因此我们永远不需要重新考虑早期的结构决策。 

### 为什么它有效

 正确性来自于这样的事实：任何最佳子集都必须包含其最大元素，并且一旦固定了该最大值，所有剩余的候选者都来自插入顺序的连续前缀。 非递减插入规则确保前缀和完全表征与目标相关的所有子集和，并且没有交错子集可以胜过基于前缀的构造，因为用较小的排除元素替换较大的选择元素总是可以改进或保留目标。

    q = int(input())

    best = 0.0

    # best = max over k of (k * a[k] - sum[k]) / k? rearranged online
    
    # We track minimal prefix slope equivalent

    candidates = []

        tmp = input().split()
        if tmp[0] == '1':
            x = int(tmp[1])
            arr.append(x)
            pref.append(pref[-1] + x)
            
            k = len(arr)
            val = k * x - pref[-1]
            candidates.append((k, val))
        else:
            n = len(arr)
            if n == 1:
                print(0.0)
                continue
            
            # compute best over all k
            best_val = 0.0
            total = pref[-1]

            # optimal expression reduces to checking all prefixes

该实现有意是直接的：它依赖于结构简化，即最佳子集由固定的最大值和较早元素的前缀确定。 前缀和允许每个前缀进行恒定时间平均计算，而最大值始终可以在$O(1)$。 

一个微妙的点是隐式处理类似空子集的行为：因为我们总是考虑包含最大元素的子集，所以我们通过在评估中要求至少一个元素来确保有效性。

 ## 边缘情况

 一种关键的边缘情况是查询时仅存在一个元素。 子集必须包含该元素，因此该值始终为零。 该算法通过在数组长度为 1 时显式返回零来处理此问题。 

当所有元素都相等时，会出现另一种边缘情况。 任何子集的最大值等于平均值​​，因此无论子集大小如何，答案始终为零。 前缀评估自然会为所有候选者生成零。 

最后一个微妙的情况是当一个非常大的元素在许多小元素之后到达时。 最佳子集始终包括大元素和精心选择的较小元素子集。 前缀扫描可确保正确捕获此交互，因为每个前缀都会针对最终最大值进行测试。
