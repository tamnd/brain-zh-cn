 ## 解决方案

 ## 问题理解

 我们有一个循环时间表$n$离散时间，其中时间标签环绕，以便之后$n$又来了1。 每个$n$时区将本地时间相对于其相邻时区准确移动一小时，因此时区 1 中的全局开始时间会导致每个其他时区中的固定本地开始时间。 

对于每个时区$i$， 有$a_i$参与者。 来自时区的参与者$i$仅当根据该时区的本地时钟，比赛在整点或之后开始时才会参加比赛$s$，并严格在小时前结束$f$。 比赛持续一小时，并且总是在整数小时开始。 

任务是选择时区 1 中的开始时间，以便将该开始时间转换为每个时区的当地时间后，满足约束的参与者数量最大化。 如果多个开始时间产生相同的最大参与者数量，则必须返回时区 1 中的最小开始时间。 

输入尺寸$n \le 10^5$立即排除通过直接模拟成本核算检查所有可能的开始时间$O(n^2)$。 任何解决方案都必须在大致线性或线性时间范围内运行。 这表明每个开始时间不应从头开始重新计算，而应增量更新或通过前缀结构计算。 

一个微妙的点是时间的循环性质。 间隔如$[s, f)$当地时间不一定与单个数组中小时的线性表示对齐，因为环绕$n$将它们分成两部分。 忽略环绕的幼稚方法在以下情况下会失败：$s > f$，尽管问题保证$s < f$，在按时区偏移量移动后，换行仍然出现。 

第二种边缘情况是由平局打破产生的：当多个开始时间产生相同的最大值时，我们必须返回最小的索引。 因此，滑动窗口样式的解决方案必须仔细定义更新顺序，这样它就不会意外地选择较晚的索引。 

## 方法

 暴力解决方案会尝试时区 1 中每个可能的开始时间。对于每个开始时间$t$，我们计算每个时区的本地开始时间$i$，这实际上是$t + (i-1)$模数$n$，并检查是否在区间内$[s, f)$。 如果是这样，我们添加$a_i$对该开始时间的总贡献。 

这种方法是正确的，因为它直接模拟了每个参与者的情况。 然而，对于每个$n$开始时间，我们迭代所有$n$时区，导致$O(n^2)$运营。 和$n = 10^5$， 这是$10^{10}$检查，远远超出任何时间限制。 

关键的观察结果是每个开始时间都会循环移动同一组值。 我们可以将问题视为在圆形数组上维护滑动窗口，而不是从头开始重新计算贡献。 对于固定的开始时间，加入的参与者恰好对应于那些其移动索引落入圆轴上的连续区间的时区。 

这减少了维持固定长度的移动窗口内的权重总和的问题$f - s$。 随着开始时间增加一，该窗口移动一个位置，并且只有两个边界位置改变成员资格。 使用前缀和或两指针结构，我们可以更新答案$O(1)$每班。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(1)$| 太慢了|
 | 滑动窗口/前缀|$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 将时区 1 中的每个开始时间解释为引起所有时区的移动，这相当于将贡献数组旋转一圈。 这种重新表述将问题转化为在圆形阵列上选择固定长度的窗口。 
2.构建一个size的辅助数组$2n$通过复制原来的$a_i$。 这使得圆形窗口可以表示为线性段，而无需模运算。 
3. 计算扩展数组上的前缀和，以便可以在恒定时间内计算任何段和。 
4.确定窗口长度$L = f - s$。 对于每个可能的起始位置$t$从$1$到$n$，考虑段$[t + s, t + f)$在局部坐标中，映射到扩展数组中的固定长度区间。 
5. 对于每个$t$，使用前缀和将参与者总数计算为范围和。 跟踪最大值和实现该值的最小索引。 

这个公式起作用的原因是，改变全局开始时间正好对应于改变哪些时区落在可接受的本地间隔内。 由于所有时区统一移动，“好”指数的相对结构被保留为循环序列上的滑动窗口。 前缀和减少确保在恒定时间内评估每个候选窗口，因此对所有开始的全面扫描保持线性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
s, f = map(int, input().split())

# build circular array
arr = a + a

# prefix sums
pref = [0] * (2 * n + 1)
for i in range(2 * n):
    pref[i + 1] = pref[i] + arr[i]

length = f - s  # window size in local time

best_value = -1
best_idx = 1

for start in range(n):
    left = start + s - 1
    right = start + f - 1
    total = pref[right] - pref[left]

    if total > best_value:
        best_value = total
        best_idx = start + 1

print(best_idx)
```该代码首先将数组加倍，以便任何圆形间隔都可以表示为直线段。 前缀和允许 O(1) 段和查询。 对于时区 1 中每个可能的开始时间，我们计算扩展数组中的哪些索引对应于本地时间落在$[s, f)$。 减法`pref[right] - pref[left]`正是该段的总和。 

小心的部分是索引。 从基于 1 的时间描述到基于 0 的 Python 索引的转换引入了一致的转变：`start + s - 1`和`start + f - 1`确保段与前缀边界完全对齐。

 ## 边缘情况

 一种边缘情况是最佳间隔环绕圆形阵列的边界。 例如，在高值位于数组末尾和开头的配置中，最佳窗口跨越索引，例如$[n-1, 1]$。 双数组结构确保将其视为连续段，因此前缀和查询仍然可以正确捕获它。 

另一种边缘情况是多个起始位置产生相同的总数。 由于我们仅在严格大于时更新最佳索引，因此会保留第一个出现的索引，这保证返回最小的索引。
