 ## 解决方案
 ## 问题理解

 我们给出了一个有向结构$n$节点，其中每个节点只有一个出边。 具体来说，平面$i$指向平面$f_i$，这意味着它“喜欢”另一架飞机。 自循环是明确禁止的，因此没有节点指向自身。 

任务是确定是否存在长度正好为三的有向循环。 换句话说，我们正在寻找三个不同的平面$A, B, C$这样$A \to B$,$B \to C$， 和$C \to A$。 

该结构是一个函数图，因为每个节点的出度都是 1。这立即意味着每个连接的组件都由一个循环组成，其中有向树馈入其中。 然而，这里只有长度为 3 的循环很重要。 

约束条件$n \le 5000$足够小以至于$O(n^2)$甚至是一个简单的$O(n)$对每个节点进行持续检查的扫描就足够了。 任何立方体或涉及每个节点重复遍历的东西仍然会通过，但没有必要。 

微妙的边缘情况来自于对遍历方向的误解。 由于每个节点都指向一个节点，但多个节点可以指向同一个目标，因此以无向的方式思考或假设对称性将破坏正确性。 

另一个边缘情况是假设任何周期都合格。 例如，长度为 2 的循环$1 \to 2 \to 1$无效。 仅计算 3 个周期的长度。 

陷阱的具体示例：

 输入：```
3
2 1 2
```这形成$1 \to 2 \to 1$， 和$3 \to 2$。 存在一个环，但长度为2，所以正确的输出是：```
NO
```停留在“循环存在”的简单循环检测方法会错误地回答“是”。 

## 方法

 一个蛮力的想法是尝试每个有序的三元组$(i, j, k)$并检查是否$i \to j$,$j \to k$， 和$k \to i$。 通过直接在数组中查找来实现很简单$f$。 然而，这需要$O(n^3)$检查，因为有$n^3$可能的三元组，并且每次检查都是恒定时间。 和$n = 5000$，这的顺序是$1.25 \times 10^{11}$检查，远远超出了时限。 

我们可以通过观察图的结构来消除不必要的搜索。 由于每个节点只有一个出边，从任何节点开始$i$，只有一个可能的链可以遵循：$i \to f_i \to f_{f_i} \to \dots$。 如果存在3个周期，它一定出现在这个确定性的链结构中。 

这建议对每个节点进行直接检查。 对于每个节点$i$，我们可以定义：

 -$a = f_i$-$b = f_a$-$c = f_b$那么我们只需要验证是否$c = i$。 如果是这样，我们就发现了一个 3 循环：$i$,$a$， 和$b$。 由于每个节点都只有一个输出边，因此将从其中一个节点开始检测每个潜在的 3 周期。 

这将问题减少到$O(n)$检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（所有三元组）|$O(n^3)$|$O(1)$| 太慢了|
 | 每个节点直接 3 步检查 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1.读取数组$f$，根据需要调整基于 0 的索引。 这确保了我们可以在恒定的时间内访问后继者。 
2.对于每个节点$i$，计算其第一次、第二次和第三次跳跃：$a = f[i]$,$b = f[a]$， 和$c = f[b]$。 这正好模拟了三次跟随有向边。 
3. 检查是否$c == i$。 如果这个成立，我们就闭合了一个长度为 3 的有向循环，起始点和结束点为$i$。 
4. 如果有这样的情况$i$满足条件，立即输出YES。 这一提前退出是有效的，因为存在一个有效的三角形就足够了。 
5. 如果没有节点产生有效的 3 步返回，则输出 NO。 

### 为什么它有效

 每个节点只有一个出边，因此每个长度为 3 的循环必须由其起始节点唯一表示。 如果一个循环$A \to B \to C \to A$存在，那么从$A$将确定性地产生$f_A = B$,$f_B = C$， 和$f_C = A$，使检查成功。 由于所有转换都是确定性的，因此不会错过任何循环，并且不会发生误报，因为条件在恰好三个步骤后明确强制关闭。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
f = list(map(int, input().split()))

# convert to 0-based indexing
for i in range(n):
    f[i] -= 1

for i in range(n):
    a = f[i]
    b = f[a]
    c = f[b]
    if c == i:
        print("YES")
        sys.exit()

print("NO")
```关键的实现细节是立即转换为基于 0 的索引。 这避免了遍历过程中重复的 -1 调整并保持数组访问干净。 

另一个重要的一点是提前退出。 一旦找到有效的三角形，我们立即终止，因为问题只要求存在，而不要求枚举。 

三级跳逻辑直接反映了数学条件$f(f(f(i))) = i$，这是函数图中 3 循环的定义属性。 

## 工作示例

 ### 示例 1

 输入：```
5
2 4 5 1 3
```我们跟踪每个节点：

 | 我| a = f[i] | b = f[a] | c = f[b] | c = f[b] | c == 我 |
 | ---| ---| ---| ---| ---|
 | 0 | 1 | 3 | 0 | 是 |

 在$i = 0$，我们得到$0 \to 1 \to 3 \to 0$，形成有效的3个周期。 

这证实了算法正确地识别了存在的循环。 

### 示例 2

 输入：```
3
2 1 2
```| 我| a = f[i] | b = f[a] | c = f[b] | c = f[b] | c == 我 |
 | ---| ---| ---| ---| ---|
 | 0 | 1 | 0 | 1 | 否 |
 | 1 | 0 | 1 | 0 | 否 |
 | 2 | 1 | 0 | 1 | 否 |

 没有起始节点能够在三步内返回到自身，因此不存在 3 周期。 

这表明较短的周期（此处长度为 2）不会产生误报。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    f = list(map(int, input().split()))
    for i in range(n):
        f[i] -= 1

    for i in range(n):
        a = f[i]
        b = f[a]
        c = f[b]
        if c == i:
            return "YES"
    return "NO"

# provided sample
assert run("5\n2 4 5 1 3\n") == "YES"

# no cycle of length 3
assert run("3\n2 1 2\n") == "NO"

# minimal n
assert run("2\n2 1\n") == "NO"

# simple 3-cycle
assert run("3\n2 3 1\n") == "YES"

# larger with embedded triangle
assert run("4\n2 3 1 2\n") == "YES"

 ## 边缘情况

 关键的边缘情况是图包含循环但长度不为 3。例如，纯 2 循环如下：```
3
2 1 2
```从每个节点开始，该算法精确计算三个转换。 对于节点 1：$1 \to 2 \to 1 \to 2$，它不会返回到 1，因此被正确拒绝。 所有节点都会发生同样的情况，因此输出为 NO。 

另一种边缘情况是多个节点馈入有效的 3 周期。 该算法仍然有效，因为它不依赖于可达性或连接性，仅依赖于直接的功能组合。 对于环路内的任何节点，三重跳将停留在环路内并正确返回，即使环路不是孤立的，也能确保检测到。
