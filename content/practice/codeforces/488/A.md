 ## 解决方案
 ## 问题理解

 我们正站在一座非常大的塔楼的整数楼层，该塔楼的延伸范围远远低于零，也远高于零。 从我们现在的楼层开始$a$，我们只允许向上移动，这意味着我们重复添加正整数。 目标是找到最小的正步长$b$这样地板$a + b$其十进制表示形式中至少包含一位数字 8。 

所以任务不是自由地搜索楼层，而是从一个固定点开始，严格向上移动，直到找到第一个十进制数字包含 8 的数字。 

输入约束$|a| \le 10^9$意味着起点足够小，我们可以安全地模拟向上移动，而不必担心溢出或极大的迭代计数。 在最坏的情况下，我们可能需要检查数字，直到遇到幸运的数字，但由于“幸运”取决于数字结构而不是算术大小，因此这些数字的密度足以让直接扫描在限制范围内通过。 

主要微妙的边缘情况是要求$b$必须严格为正。 即使起始数字已经包含 8，我们也无法输出零。 例如，如果$a = 8$，我们仍然必须向上移动到 9 或更高，尽管 8 已经“幸运”，但答案至少是 1。 

当跨越数字边界（如 79 → 80 或 799 → 800）时，会出现另一种边缘情况。天真的假设幸运数字稀疏可能会导致过度思考，但实际上我们只是按顺序检查每个整数。 

## 方法

 一个直接的解决方案是模拟从起始楼层向上行走。 对于每一步，我们都会增加当前楼层并检查其十进制表示形式是否包含数字 8。第一次满足此条件时，我们返回行驶的距离。 

这种方法是正确的，因为它遵循字面定义：我们被要求提供最小的正偏移量，并且按升序检查整数可以保证第一个有效的遇到是最佳的。 

暴力的本质是显而易见的，但在这里也是无害的。 在最坏的情况下，如果幸运数字极其罕见，我们可能会扫描很大的范围。 然而，包含数字 8 的数字出现的频率足够高，因此预期的检查次数很小，而且即使是最坏情况的行为也受到以下事实的限制：在任何大小为 10 的块中，每个数字都出现在该范围内的每个位置中。 

不需要像数字 DP 这样的高级优化，因为我们不是计算或构造所有有效数字，只是从单个点向前搜索。 

关键的简化是认识到问题纯粹是顺序的：我们不需要推理“这个数字是否包含 8”之外的结构。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(k·d) 其中 k 是到下一个幸运数字的距离 | O(1) | O(1) | 已接受 |
 | 最佳| O(k·d) | O(1) | O(1) | 已接受 |

 这里$d$是位数，最多为 10。 

## 算法演练

 1.从指定楼层开始$a$。 我们将探索严格大于$a$， 自从$b$必须是积极的。 
2. 初始化计数器$b = 0$，代表我们向上移动了多远。 
3. 重复增加当前楼层和计数器：从$a + b$到$a + b + 1$，然后增加$b$by 1. 这确保我们总是按升序检查下一层。 
4. 对于每个新的下限值，将其转换为字符串并扫描其数字以检查是否有任何数字等于“8”。 字符串转换的原因是数字提取对于此约束来说是最简单且恒定因子有效的。 
5、如果发现数字8，立即停止并输出$b$，因为这是我们第一次到达幸运楼层。 排序保证了最小化。 

### 为什么它有效

 我们正在以严格递增的顺序扫描整数，从$a+1$。 每个候选楼层都被检查一次，并且我们在第一个满足“包含数字 8”条件的楼层处停止。 由于搜索空间是完全有序的并且我们单调地进行，因此第一次命中必须对应于最小正距离。 没有跳过的值可以产生更小的有效值$b$，因此正确性直接来自有序枚举。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

a = int(input().strip())

b = 0
while True:
    b += 1
    x = a + b
    if '8' in str(x):
        print(b)
        break
```代码完全遵循算法。 循环从 1 开始，因为我们必须确保$b$。 每次迭代向上移动一层并立即检查数字状况。 

转换`str(x)`是安全的，因为数量保持在合理范围内。 条件`'8' in str(x)`是测试数字存在的最简单方法，无需手动提取数字。 

一旦找到第一个有效数字，循环就会终止，因此除了答案之外不会执行不必​​要的计算。

 ## 边缘情况

 一种重要的边缘情况是起始数字已包含数字 8。对于输入$a = 8$，算法开始于$b = 1$, 检查$9$，并且只会继续前进。 尽管8本身很幸运，但它是无法达到的，因为$b$必须是积极的。 第一个有效输出是$b = 1$因为 9 不包含 8 但 18 出现得更晚； 然而实际的第一个是 18，给出$b = 10$。 循环自然会处理这个问题，因为它从不考虑$a$本身。 

另一个边缘情况是负起始值。 例如，$a = -1$。 顺序如下$-1, 0, 1, 2, \dots$最终达到 8。该算法不会特殊对待符号，因为数字检查适用于包括减号的绝对字符串表示形式，但由于 '-' 在`'8' in str(x)'`，保留正确性。 

最后一个微妙的情况是跨越数字边界，例如 79 到 80 到 81。该方法不依赖算术模式，因此数字变化发生在哪里并不重要。 每个整数都是独立检查的，因此不能跳过任何幸运数字。
