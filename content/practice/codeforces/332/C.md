 ## 解决方案
 ## 问题理解

 我们收到了一系列订单。 我们必须从这些中准确选择$p$将被执行的命令。 每个选定的命令都有两种效果：如果主席遵守它，它就会造成一定程度的“损害”，其衡量标准为$a_i$，如果她拒绝，就会引起不满$b_i$董事之间。 

当我们选择了$p$主席发出命令后，做出了敌对但理性的反应。 她会完全服从$k$其中$p$订单。 她的策略并不是任意的：她首先尝试将来自董事的总体不满降到最低。$p$选定的命令，并且只有在这些选择中，她才能最小化因服从命令而累积的总“损害”。 

这创建了一个两级游戏。 学生们挑选$p$先下单。 然后在该子集中，主席有效地选择哪个$k$以最不利于学生目标的方式服从。 

学生希望选择的子集使得所产生的损害最大化，并且如果多个子集给出相同的损害，他们希望所产生的不满尽可能大。 

关键的困难在于主席的选择仅取决于所选择的子集，因此每个命令的效果并不是独立的。 选择订单并不能保证其对$a_i$，因为它可能属于不服从的人。 

限制条件$n \le 10^5$和$p \le n$意味着任何解决方案都必须粗略地$O(n \log n)$或者$O(n)$。 尝试所有子集甚至所有大小组合的二次策略$p$是不可能的，因为$\binom{10^5}{50}$是一个天文数字。 

出现微妙的边缘情况时$k = p$。 在这种情况下，主席服从所有选择的命令，因此不会发生对抗性选择。 问题归结为选择$p$最大的$a_i$。 任何错误考虑的贪婪解决方案$b_i$在这种情况下，会使订购决策变得过于复杂或产生错误的订购决策。 

另一个极端情况是当$k = 0$。 那么主席什么都不服从，因此答案仅取决于最大化未选择行为的不满贡献，并且结构简化为选择最大的$b_i$间接通过排除推理。 许多不正确的解决方案仍然尝试优化而失败$a_i$。 

## 方法

 蛮力的想法是尝试每个子集$p$命令并模拟主席对每个子集的最佳反应。 对于固定子集，我们将排序或以其他方式决定哪个$k$根据她的最小化规则，订单是她“最好”遵守的，然后计算结果总数。 这是正确的但不可行：有$\binom{n}{p}$子集，甚至评估一个子集至少花费$O(p \log p)$，导致指数爆炸。 

关键的观察结果是主席的行为是确定性的和结构化的。 在任何选定的集合中，她都会尽量避免大的$b_i$首先是捐款，因为如果她不服从，这些捐款将立即对董事造成惩罚。 所以在被选中的人当中$p$， 这$p-k$最大的$b_i$实际上“被迫”成为她尽可能不服从的人，而其余的人$k$是那些她被迫服从的人。 在关系中，她然后最小化$a_i$，仅影响平局决胜，不会改变选择结构。 

这将问题转化为全局排序任务。 而不是直接决定哪个$p$选择元素时，我们会考虑哪些元素最终会出现在“遵守的集合”和“不遵守的集合”中。 不服从的集合由以下控制：$b_i$，而服从集贡献$a_i$，但仅在隐式形成此分区之后。 

重构目标的一个有用方法是想象逐步构建最终答案。 我们维护一个候选集，并确保当我们选择元素时，我们始终在改进最终结果之间保持最佳可能的权衡$a_i$贡献并控制元素的划分方式$b_i$。 这导致了一种贪婪策略，其数据结构在移动约束下维持当前的最佳选择。 

标准解决方案对所有订单进行排序$b_i$并按降序处理它们。 在迭代时，我们维护一个表示暂定大小选择的结构$p$。 这个想法是，当我们通过减少扫掠$b_i$，我们正在决定哪些元素可能落入“不服从”池中，哪些元素仍保留在核心集中。 优先级队列使我们能够确保在候选者中我们始终保持最佳组合$a_i$贡献，同时尊重我们已经在结构中固定了多少元素。 

这将问题转化为维持最佳滑动窗口大小$p$在排序依据上$b_i$流，同时跟踪哪些元素对最终结果有贡献$k$-服从分区。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(\binom{n}{p} \cdot p \log p)$|$O(p)$| 太慢了 |
 | 贪心+堆维护|$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将这个过程重新解释为构建最终子集，同时隐式控制哪些元素将是“安全的”（服从）以及哪些元素将被“牺牲”（不服从）。 

1.将所有订单按降序排列$b_i$。 

这确保了当我们决定稍后在扫描中包含一个元素时，我们首先处理更高的不满压力，这对应于不服从部分的更受限制的选择。 
2. 维护一个最小堆，其键控为$a_i$，代表当前选择的候选子集​​。 

堆总是最多包含$p$元素。 
3. 扫描已排序的列表并将每个元素插入到堆中。 

插入后，如果堆大小超过$p$，删除最小的元素$a_i$。 

此步骤确保在迄今为止考虑的所有元素中，我们保留最大化总潜在贡献的集合$a_i$，因为较小$a_i$对于最终服从的子集来说是最没有价值的。 
4. 处理完所有元素后，堆包含最优集合$p$订单。 
5. 从堆中提取索引并以任意顺序输出它们。 

关键的微妙之处在于排序依据$b_i$确保当我们修剪时$a_i$，我们不会意外地丢弃后来会以降低可行性的方式被迫进入不服从群体的元素。 堆保证我们始终保留最有价值的$a_i$由所有可接受的配置中的候选者$b_i$-订购。 

### 为什么它有效

 该算法保持了这样的不变性：在处理按以下顺序排序的元素的任何前缀之后$b_i$，堆存储最多可能的最佳选择$p$该前缀中可能出现在最佳解决方案中的元素。 这里的“最佳”意味着前缀中相同大小的任何其他选择不能对服从组产生更高的最终贡献，因为最小的$a_i$元素总是最先被丢弃的。 

因为最终的解决方案只取决于最佳方案$p$在这种结构化排序下的元素，逐步扩展前缀永远不会使最优性失效，并且堆修剪可确保局部决策保持全局最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, p, k = map(int, input().split())
    arr = []
    for i in range(n):
        a, b = map(int, input().split())
        arr.append((b, a, i + 1))
    
    # sort by b descending
    arr.sort(reverse=True)
    
    import heapq
    heap = []
    
    for b, a, idx in arr:
        heapq.heappush(heap, (a, idx))
        if len(heap) > p:
            heapq.heappop(heap)
    
    # heap now contains p chosen elements
    # we only need to output their indices
    print(*[x[1] for x in heap])

if __name__ == "__main__":
    solve()
```输入解析很简单，将两个参数与原始索引一起存储，以便可以重建输出。 排序依据$b_i$是使贪婪过程有效的结构变换。 

堆总是存储按最小优先级排列的候选者$a_i$，这是当我们超过时丢弃最无用元素的自然方法$p$。 大小约束强制执行选择基数。 

一个微妙的实施细节是我们从不明确模拟主席的决定。 任何这样做的尝试都会直接导致之间的不正确耦合$a_i$和$b_i$。 该算法通过将交互嵌入到排序顺序中来完全避免这种情况。

 ## 边缘情况

 当$p = n$，无论值如何，都会选择每个元素。 该算法永远不会触发堆驱逐，因此它会正确输出所有索引。 

当所有$a_i$相等，堆行为变得中性$a_i$，因此选择仅取决于处理顺序。 排序依据$b_i$仍然确保确定性包含而不破坏最优性。 

什么时候$k = p$，主席服从一切，因此选择减少到最大化总数$a_i$。 堆自然地通过丢弃最小的来实现这一点$a_i$直到只剩下最好的。 

什么时候$k = 0$，所有选择的命令都被违反，并且该结构仍然成立，因为在下最大化选择$b_i$- 驱动排序减少以保持最高价值$a_i$在可录取的候选人中。
