 ## 解决方案
 ## 问题理解

 我们得到一个排在一条线上的数字列表，其中每个位置代表一条定律，其值代表它的“有用”或“价值”。 我们必须恰好选择两个连续的固定长度块`k`。 这两个块不能重叠，我们希望两个块内所有值的总和尽可能大。 

另一种看待它的方式是我们正在滑动一个大小的窗口`k`遍历数组并在每个有效的起始位置计算其总和。 从这些窗口总和中，我们必须选择两个窗口，使得它们的索引不重叠并且它们的总和最大化。 输出不是值，而是这两个窗口的起始索引，并具有优先选择较小起始索引的平局规则。 

约束很大，元素多达 200,000 个。 任何尝试所有窗口对的解决方案都需要粗略检查$O(n^2)$组合，这太慢了。 甚至$O(nk)$在最坏的情况下，重复重新计算窗口总和的解决方案也会失败。 这迫使我们寻求线性或近线性解决方案，通常$O(n)$或者$O(n \log n)$。 

一些边缘情况很容易被忽略。 如果所有值都相同，则任何一对有效段都是最佳的，但打破平局规则迫使我们选择最早可能的第一段，然后选择最早兼容的第二段。 当最好的两个片段相邻而不是稍微分开时，就会发生另一种微妙的情况。 一个天真的贪婪选择可能会选择一个局部最好的第二段，从而阻止全局更好的配对。 

例如，考虑：```
n = 5, k = 2
values = [5, 1, 5, 1, 5]
```最佳选择是从 1 和 3（或 3 和 5）开始的段，但是首先贪婪地选择最佳的单个段可能会阻止最佳对。 

关键的困难在于，最佳的第二段取决于第一个段的结束位置，因此我们需要一种结构，使我们能够有效地将最佳前缀选择与后缀扫描结合起来。 

## 方法

 暴力破解的想法很简单：计算每个长度子数组的总和`k`，存储它们，然后尝试每对不重叠的子数组。 如果有关于`n`可能的子数组，然后检查所有对是$O(n^2)$，每张支票都是$O(1)$，所以总复杂度是$O(n^2)$，对于 200,000 来说太大了。 

我们可以通过观察来改进这一点，一旦我们知道每个窗口大小的总和`k`，问题简化为选择两个索引`i < j - k + 1`最大化`sum[i] + sum[j]`。 我们可以预先计算每个位置的最佳第一段，而不是尝试所有对`j`第二段开始的地方。 

对于每个位置`j`，我们想知道最好的`i`在它的左边。 这自然意味着在窗口总和上保持前缀最大值。 然后对于每个`j`，我们将其与最佳有效值配对`i`在它之前并计算答案。 

这将问题从二次配对减少到具有预先计算的窗口总和和前缀最佳位置的单遍。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了 |
 | 前缀优化 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们首先将数组转换为窗口和数组，其中每个索引代表长度为的子数组的和`k`。 

1. 计算输入数组的前缀和，以便可以在恒定时间内计算任何窗口和。 这避免了重复重新计算总和并确保我们整体保持线性。 
2. 构建数组`w`， 在哪里`w[i]`是从以下位置开始的线段的总和`i`（1-索引）。 每个值代表在该位置选择段的“分数”。 
3. 创建数组`best_left`， 在哪里`best_left[i]`存储从以下位置开始的所有窗口中最佳窗口的索引`1`到`i`。 “最好”是指数额最大； 如果相等，我们保留较小的索引。 这种前缀结构使我们能够立即知道任何第二段位置的最佳第一段。 
4. 迭代第二段的所有有效起始位置。 对于第二段开始于`i`，第一个段必须在开始之前结束，因此最后一个有效的开始是`i - k`。 
5. 对于每个有效`i`，将总价值计算为`w[i] + w[best_left[i - k]]`并跟踪最大值。 通过优先选择较小的第一个索引，然后选择较小的第二个索引来应用平局打破。 
6. 输出存储的两个起始位置。 

关键思想是，当我们修复第二段时，最佳的第一段已经通过前缀最大值在恒定时间内已知。 

为什么它有效：在每个位置`i`,`best_left[i]`存储所有有效候选者中的最佳第一段。 任何最佳对的第一段都必须在该范围内，并且将其与固定的第二段配对不会影响其内部最优性。 这将全局优化问题简化为前缀和后缀分割上的独立局部决策。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

# prefix sums
pref = [0] * (n + 1)
for i in range(n):
    pref[i + 1] = pref[i] + a[i]

# window sums
w = [0] * (n - k + 1)
for i in range(n - k + 1):
    w[i] = pref[i + k] - pref[i]

# best position to the left
best_left = [0] * len(w)
best_left[0] = 0

for i in range(1, len(w)):
    if w[i] > w[best_left[i - 1]]:
        best_left[i] = i
    else:
        best_left[i] = best_left[i - 1]

best_i = 0
best_j = k
best_val = -1

for j in range(k, len(w)):
    i = best_left[j - k]
    val = w[i] + w[j]
    if val > best_val:
        best_val = val
        best_i = i
        best_j = j
    elif val == best_val and (i < best_i or (i == best_i and j < best_j)):
        best_i = i
        best_j = j

print(best_i + 1, best_j + 1)
```前缀数组是标准的，确保每个窗口总和在恒定时间内计算。 数组`w`将问题压缩为选择两个元素而不是两个段。 

这`best_left`数组是关键的结构：它确保对于每个可能的第二段，我们可以立即检索最佳有效的第一段，而无需扫描。 

通过在匹配总和后比较索引，在最终循环中显式处理平局打破。 

## 工作示例

 ### 示例 1

 输入：```
5 2
3 6 1 1 6
```窗口总和：

 | 我| 窗口| 总和|
 | --- | --- | --- |
 | 0 | [3,6]| 9 |
 | 1 | [6,1]| 7 |
 | 2 | [1,1]| 2 |
 | 3 | [1,6]| 7 |

 现在构建`best_left`：

 | 我| w[i] | 最佳左[i] |
 | --- | --- | --- |
 | 0 | 9 | 0 |
 | 1 | 7 | 0 |
 | 2 | 2 | 0 |
 | 3 | 7 | 0 |

 对于每个第二段：

 - j = 2：[0..0] 中最好的 i → i=0，总计 = 9 + 2 = 11
 - j = 3：[0..1] 中最好的 i → i=0，总计 = 9 + 7 = 16

 最佳对是 0 索引形式的 (0, 3) → (1, 4)。 

这显示了前缀选择如何确保我们在评估后面的位置时不会错过全局最优的第一段。

| j | 最好的我| 对和 |

 ## 边缘情况

 当所有值都相同时，每个窗口都有相同的分数。 前缀最大数组始终保留最早的索引，因此第一个段尽早固定，第二个段成为其之后的最早有效位置。 这完全符合打破平局的要求。 

当最好的两个窗口相邻而不是相距稍远时，算法仍然可以正确运行，因为相邻性仅通过索引分离而不是通过偏好来强制执行。 即使稍后的窗口是局部最优的，它在构建时也不会替换全局最优的较早的前缀`best_left`。 

对于小输入，例如`n = 2k`，恰好有一对有效的段，并且该算法正确地简化为选择该对，没有任何歧义。
