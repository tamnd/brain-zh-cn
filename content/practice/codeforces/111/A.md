 ## 解决方案
 ## 问题理解

 我们需要构造一个数组`n`正整数。 该数组必须同时满足两个条件。 

所有元素的平方和必须至少为`x`，而元素的普通总和不得超过`y`。 

任务不是优化任何东西。 我们只需要找到一种有效的构造，或者确定不存在构造。 

这些限制立即排除了任何昂贵的搜索。 的价值`n`可以达到`10^5`，所以任何二次或指数都是不可能的。 的价值`x`特别大，直到`10^12`，这意味着暴力破解候选数组是完全不现实的。 我们需要一个可以在线性时间内计算的直接数学结构。 

关键细节是平方条件的增长速度比普通总和快得多。 单个大数对平方和的贡献巨大，而对普通和的贡献仅呈线性。 这一观察结果强烈建议将大部分价值集中到一个元素中，而不是均匀地分散它。 

一些边缘情况很容易被错误处理。 

考虑：```
1 10 3
```我们需要一个正整数，其平方至少为`10`，但其值最多为`3`。 唯一可能的元素需要同时满足：```
a^2 >= 10
a <= 3
```不存在这样的整数，因为`3^2 = 9`。 正确的输出是：```
-1
```粗心的实现可能只检查平方条件并打印`4`，忘记违反了总和限制。 

另一个微妙的情况是当最小可能总和已经超过`y`。```
5 100 4
```所有数字都必须是正数，因此最小可能的和已经是`5`。 自从`5 > 4`，无论怎样，答案都是不可能的`x`。 正确的输出是：```
-1
```仅关注平方要求的实现可能会错过这种立即不可能的情况。 

另一个棘手的例子：```
3 11 5
```一个天真的想法是均匀分配值，例如`[2,2,1]`。 总和有效：```
2 + 2 + 1 = 5
```但平方和仅为：```
4 + 4 + 1 = 9
```这太小了。 有效的构造是：```
3 1 1
```因为：```
9 + 1 + 1 = 11
3 + 1 + 1 = 5
```这说明了为什么将价值集中到一个元素比分散它更强大。 

## 方法

 暴力方法会尝试生成数组并检查它们是否满足两个不等式。 即使我们将每个元素最多限制为`y`，数组的数量仍然是一个天文数字。 例如，与`n = 20`和`y = 20`, 已经有`20^20`可能的数组。 这是完全不可行的。 

暴力破解的想法在概念上是可行的，因为检查候选数组很容易。 我们可以在线性时间内计算两个总和。 问题在于搜索空间。 

突破来自于理解方块的行为方式。 假设我们已经确定了总金额。 在具有该总和的所有数组中，将尽可能多的值放入一个元素中可以最大化平方和。 

例如：```
5^2 = 25
```尽管：```
3^2 + 2^2 = 13
```将数字分成更小的部分会减少平方贡献。 

这意味着最好的策略非常简单。 制作`n - 1`元素等于`1`，因为所有数字都必须是正数。 将其他所有内容放入一个大元素中。 

设那个大元素为`k`。 

然后：```
sum = k + (n - 1)
square_sum = k^2 + (n - 1)
```我们需要：```
k^2 + (n - 1) >= x
k + (n - 1) <= y
```最小有效值`k`平方条件为：```
k >= ceil(sqrt(x - (n - 1)))
```如果那样的话`k`也满足总和约束，我们有一个有效的构造。 否则，不存在解决方案。 

这将整个问题简化为一些算术运算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳| O(n) | O(1) 不包括输出 | 已接受 |

 ## 算法演练

 1. 阅读`n`,`x`， 和`y`。 
2. 储备`n - 1`元素为`1`。 

这是这些位置的最小可能贡献，因为所有数字都必须是正数。 
3. 设剩余元素为`k`。 

总平方和变为：```
k^2 + (n - 1)
```4. 计算最小值`k`满足平方条件。 

我们需要：```
k^2 >= x - (n - 1)
```所以：```
k = ceil(sqrt(x - (n - 1)))
```如果`x - (n - 1)`已经是非正数，那么`k = 1`就足够了。 
5. 检查是否满足普通和约束。 

总和为：```
k + (n - 1)
```如果这超过`y`， 打印`-1`。 
6. 否则，打印`k`其次是`n - 1`那些。 

### 为什么它有效

 该结构最小化了任何给定平方贡献的普通总和。 

假设我们想要一个大的平方和。 将价值拆分为多个数字的效率很低，因为：```
(a + b)^2 > a^2 + b^2
```对于正整数`a`和`b`。 

因此，固定普通和的最大平方贡献是通过将尽可能多的值集中到一个元素中来实现的。 通过将所有其他元素设置为`1`，我们为单个大数字留下尽可能大的预算。 

如果即使是这种最好的安排也不能同时满足两个不等式，那么就没有其他安排可以。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

n, x, y = map(int, input().split())

need = x - (n - 1)

if need <= 1:
    k = 1
else:
    k = math.isqrt(need)
    if k * k < need:
        k += 1

if k + (n - 1) > y:
    print(-1)
else:
    print(k)
    for _ in range(n - 1):
        print(1)
```实施直接跟随构造。 

首先我们预留`n - 1`职位。 他们的平方贡献也是`n - 1`，因此剩余平方要求变为：```
x - (n - 1)
```然后我们计算最小的整数`k`其正方形足够大。 使用`math.isqrt`避免浮点精度问题。`isqrt(v)`返回平方根的下限，因此如果需要，我们会加一。 

条件：```
if need <= 1:
    k = 1
```处理现有的已经几乎满足平方条件的情况。 由于所有价值观都必须保持积极，`k`不能为零。 

最终检查：```
if k + (n - 1) > y:
```是关键的不可能性测试。 即使是最平方有效的构造也会违反总和限制，因此不存在解决方案。 

输出顺序并不重要。 接受任何有效的数组。

8 <= 15

```该迹线展示了核心思想：一个大值主导平方和。

## 测试用例```python
# helper: run solution on input string, return output string
import sys
import io
import math

def solve():
    input = sys.stdin.readline

    n, x, y = map(int, input().split())

    need = x - (n - 1)

    if need <= 1:
        k = 1
    else:
        k = math.isqrt(need)
        if k * k < need:
            k += 1

    if k + (n - 1) > y:
        print(-1)
    else:
        print(k)
        for _ in range(n - 1):
            print(1)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("5 15 15\n") == "4\n1\n1\n1\n1\n"

# minimum size, impossible
assert run("1 10 3\n") == "-1\n"

# exact boundary
assert run("3 11 5\n") == "3\n1\n1\n"

# already satisfied by all ones
assert run("4 4 10\n") == "1\n1\n1\n1\n"

# impossible because minimum sum exceeds y
assert run("5 100 4\n") == "-1\n"

# large square requirement
out = run("2 1000000 2000\n")
vals = list(map(int, out.strip().split()))
assert len(vals) == 2
assert vals[0] + vals[1] <= 2000
assert vals[0] * vals[0] + vals[1] * vals[1] >= 1000000
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`1 10 3`|`-1`| 单元素不可能性 |
 |`3 11 5`|`3 1 1`| 两种条件完全相等 |
 |`4 4 10`|`1 1 1 1`| 所有这些都已经足够了 |
 |`5 100 4`|`-1`| 最小正和已经太大 |

 ## 边缘情况

 考虑输入：```
1 10 3
```该算法计算：```
need = 10
```最小有效平方根上限为：```
k = 4
```但：```
4 > 3
```所以求和条件立即失败。 该算法打印：```
-1
```这可以正确处理单元素不可能性的情况。 

现在考虑：```
5 100 4
```即使在担心平方之前，五个正整数之和也必须至少为`5`。 

该算法计算：```
need = 96
k = 10
```然后：```
10 + 4 = 14
```这超过了`y = 4`。 

该算法打印：```
-1
```这正确地反映了这样一个事实：仅总和就已经使任务变得不可能。 

最后，考虑：```
4 4 10
```保留的已经贡献了：```
3
```平方和，所以：```
need = 1
```该算法保持：```
k = 1
```和输出：```
1 1 1 1
```平方和正好是`4`，以尽可能小的值满足要求。
