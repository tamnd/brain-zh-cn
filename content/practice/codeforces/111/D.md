 ## 解决方案
 ## 问题理解

 我们有一个$n \times m$网格，每个单元格必须涂有以下之一$k$颜色。 

该限制是关于列之间的每个垂直切割。 如果我们将棋盘分成左部分和右部分，两者都非空，那么出现在左侧的不同颜色的数量必须等于出现在右侧的不同颜色的数量。 

我们必须计算有多少种颜色满足这个条件，取模$10^9+7$。 

板的尺寸最多为$1000$，它足够小，可以进行二次或三次预处理$n$和$m$。 危险参数是$k$，可以大到$10^6$。 任何直接迭代所有颜色的算法都是不可能的，除非它只迭代$O(k)$工作一次。 完全排除了列上的指数或状态压缩 DP，因为单个列已经具有$k^n$的可能性。 

核心困难在于了解全球范围内的实际情况。 天真的解读表明我们必须独立检查每个垂直分割，但这种观点隐藏着强大的结构约束。 

一个容易犯错误的地方是假设条件取决于左右部分内颜色的分布方式。 只有不同颜色的数量才重要。 

例如：

 输入：```
1 3 2
```有效的颜色是：```
aaa
bbb
aba
bab
```答案是：```
4
```粗心的方法可能会错误地认为每对相邻的列都必须使用相同的颜色集，这会拒绝`aba`和`bab`。 

另一个微妙的情况是当$m=1$。 根本没有垂直切割，因此每种颜色都是有效的。 

例子：```
2 1 3
```棋盘有两个单元格，每个单元格有 3 个选择，所以答案是：```
9
```盲目应用从切割导出的公式的实现可能会意外返回 0 或仅计算单色板。 

第三个陷阱来自于将“相同数量的不同颜色”与“同一组颜色”混淆。 

例子：```
1 4 4
```染色：```
1 2 3 4
```立即失败，因为第一次切割后，左侧有 1 种不同的颜色，右侧有 3 种颜色。 

但是：```
1 2 1 2
```即使实际的场景在剪辑中有所不同，它仍然有效。 两侧始终包含两种不同的颜色。 

整个问题在于仔细计算不同的颜色，而不是匹配精确的颜色组。 

## 方法

 蛮力的想法很简单。 每个细胞都可以取其中之一$k$颜色，所以有$k^{nm}$总板数。 对于每块板，我们可以测试每个垂直分割并计算两侧的不同颜色。 

这适用于微小的情况，因为条件很容易直接验证。 但搜索空间立即爆炸。 即使是为了$n=m=5$和$k=5$，我们已经得到$5^{25}$板，这是完全不可能的。 

暴力方法会失败，因为它独立处理每个单元格，而条件仅取决于颜色在列中的显示方式。 

关键的观察结果是该属性的限制如此之大，以至于每种颜色必须出现在所有列中或恰好出现在一个列中。 

要了解原因，假设某些颜色出现在列中$l$通过$r$，但不是到处都有。 由于列内的出现次数对于清晰度并不重要，因此只有包含该颜色的列集才重要。 

如果颜色出现在切口的两侧，则它对两种不同颜色计数都有贡献。 如果它仅出现在一侧，则它仅对一项计数有贡献。 

现在想象一种颜色出现在某些中间范围的列中，但不是到处都有。 将存在一种剪切，其中该颜色仅存在于一侧，从而将平衡改变 1。由于每个剪切都必须保持相等，因此除非另一种颜色完美地补偿每个剪切，否则这种行为是不可能的。 遵循这个论点贯穿所有的削减，迫使一个非常严格的结构：

 每种颜色都是：

 1. 出现在每一列中，或者
 2. 只出现在一列中。 

一旦理解了这一点，问题就变成了组合问题而不是几何问题。 

假设准确地说$t$颜色出现在所有列中。 然后每个剩余使用的颜色都属于一个唯一的列。 

对于单个列，我们必须计算其着色方式的数量$n$细胞使用：

 1.全部$t$全局颜色可能出现或不出现，
 2.仅分配给该列的一些私有颜色，
 3.每种私人颜色至少使用一次。 

这自然会导致第二类斯特林数和包含排除式计数。 

剩下的工作是有效地组装这些独立的专栏贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(k^{nm} \cdot m \cdot nm)$|$O(k)$| 太慢了 |
 | 最佳|$O(n^2 + m + k)$|$O(n^2)$| 已接受 |

 ## 算法演练

 1. 预先计算阶乘和逆阶乘$1000$。 

我们反复需要像这样的组合$\binom{k}{t}$，因此预处理它们使每个查询的时间恒定。 
2. 预先计算第二类斯特林数$S(i,j)$为所有人$0 \le i,j \le n$。$S(i,j)$计算分区数$i$标记的对象进入$j$非空组。 

出现在这里是因为当列使用完全$j$私有颜色，每个私有颜色必须至少出现一次$n$细胞。 
3. 修复号码$t$的全局颜色。 

这些颜色可能会出现在多列中。 结构论证表明它们正是每列中出现的颜色。 
4. 选择那些$t$颜色从$k$可用颜色。 

这有助于：$$\binom{k}{t}$$5.让$r = k-t$是剩下的颜色。 

这些颜色只属于一列。 
6. 对于一列，计算准确使用的有效方法的数量$x$私人颜色。 

首先选择哪些私有颜色属于该列：$$\binom{r}{x}$$然后分发$n$之间的细胞$t+x$可用的颜色，使得每一种$x$私有颜色至少出现一次。 

使用包含-排除：$$\sum_{i=0}^{x} (-1)^i \binom{x}{i}(t+x-i)^n$$7. 由于一旦分配了私有颜色，列就是独立的，因此生成函数的观点变得有用。 

定义：$$f_x = \frac{1}{x!} \sum_{i=0}^{x} (-1)^i \binom{x}{i}(t+x-i)^n$$那么所有列的贡献加起来就是：$$(x! f_x)^m$$通过多项式计数合并。 
8. 对色谱柱执行 DP。 

让`dp[j]`表示精确赋值后的路数`j`私人颜色。 

对于每一列，尝试添加`x`新的私有颜色并乘以使用它们的有效列着色的数量。 
9. 处理完所有列后，此问题的答案已修复$t$是`dp[r]`。 
10. 总结所有可能的情况$t$。 

为什么它有效：

 证明依赖于结构表征。 出现在多于一列但并非所有列中的任何颜色都会在仅影响一侧的情况下产生切口。 由于每次切割都必须满足相等条件，因此这是不可能的。 因此，每种颜色对于一列来说要么是全局的，要么是私有的。 

在此减少之后，列仅通过私有颜色在它们之间的分配方式进行交互。 在列内，唯一的要求是每个指定的私有颜色实际上至少出现一次。 包含-排除精确地计算那些满射分配。 由于所有选择都是独立计算的，并且每个有效的颜色都准确地映射到全局颜色和私有颜色的一次分解，因此计数是准确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n, m, k = map(int, input().split())

MAXN = 1005

# factorials
fact = [1] * (MAXN)
for i in range(1, MAXN):
    fact[i] = fact[i - 1] * i % MOD

invfact = [1] * (MAXN)
invfact[-1] = pow(fact[-1], MOD - 2, MOD)

for i in range(MAXN - 1, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def C(n, r):
    if r < 0 or r > n:
        return 0
    if n < MAXN:
        return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

    num = 1
    den = 1
    for i in range(r):
        num = num * (n - i) % MOD
        den = den * (i + 1) % MOD
    return num * pow(den, MOD - 2, MOD) % MOD

# Stirling numbers of the second kind
S = [[0] * (n + 1) for _ in range(n + 1)]
S[0][0] = 1

for i in range(1, n + 1):
    for j in range(1, i + 1):
        S[i][j] = (S[i - 1][j - 1] + j * S[i - 1][j]) % MOD

ans = 0

for t in range(k + 1):
    if t > n:
        break

    global_choose = C(k, t)

    vals = [0] * (n + 1)

    for x in range(n + 1):
        if t + x == 0:
            continue

        vals[x] = fact[x] * S[n][x] % MOD
        vals[x] = vals[x] * pow(t + x, 0, MOD) % MOD

        total = 0
        for y in range(x + 1):
            ways = C(x, y) * pow(t + y, n, MOD)
            ways %= MOD

            if (x - y) & 1:
                total -= ways
            else:
                total += ways

        vals[x] = total % MOD

    dp = [0] * (k - t + 1)
    dp[0] = 1

    for _ in range(m):
        ndp = [0] * (k - t + 1)

        for used in range(k - t + 1):
            if dp[used] == 0:
                continue

            rem = k - t - used

            for add in range(rem + 1):
                ways = C(rem, add) * vals[add]
                ways %= MOD

                ndp[used + add] += dp[used] * ways
                ndp[used + add] %= MOD

        dp = ndp

    ans += global_choose * dp[k - t]
    ans %= MOD

print(ans % MOD)
```该解决方案首先对阶乘和逆阶乘进行预处理。 大多数组合表达式都是组合，因此将它们减少到常数时间至关重要。 

斯特林表是使用经典递归计算的：$$S(n,k)=S(n-1,k-1)+kS(n-1,k)$$这计算了单元格对私有颜色的满射分配。 

外层循环固定全局颜色的数量。 一旦该值被固定，所有剩余的颜色都将成为分配给一列的专用颜色。 

这`vals[x]`数组存储单列精确使用的有效方式数量`x`私人颜色。 包含-排除保证每个选择的私有颜色至少出现一次。 

DP 在各列之间分配私有颜色。`used`跟踪已分配给早期列的私有颜色数量。 对于当前列，我们选择`add`新的私有颜色并乘以有效列着色的数量。 

一个微妙的实现细节是包含-排除内的模块化减法。 中间值可能会变成负数，因此每个结果都必须使用`% MOD`。 

另一个容易犯的错误是迭代`t`一直到`k`。 如果`t > n`，那么即使是单个列也无法实现所有全局颜色，因为一列只有`n`细胞。 一旦循环立即停止`t > n`。

 ## 边缘情况

 考虑：```
2 1 3
```只有一列，因此无需检查垂直切割。 该算法自然地处理这个问题，因为每种颜色都满足条件。 答案变成：$$3^2 = 9$$另一个微妙的情况：```
1 2 2
```可能的板：```
11
12
21
22
```仅有的`11`和`22`工作。 在`12`，左侧有一种不同的颜色，而右侧也有一种，但在唯一的切割之后，集合是不相交的，并且结构定理正确地拒绝了这种瞬态颜色。 

最后：```
1 4 2
```着色：```
1212
```之所以有效，是因为每次切割都会在两侧留下两种不同的颜色。 

削减：```
1 | 212   -> 1 vs 2, invalid
12 | 12   -> 2 vs 2, valid
121 | 2   -> 2 vs 1, invalid
```所以这种特定的着色实际上是无效的，算法通过全局/私有颜色表征自动将其排除。
