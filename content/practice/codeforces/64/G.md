 ## 解决方案
 ## 问题理解

 我们得到了一个 Unix 风格的绝对路径。 该路径被分为以下几个部分`/`，每个组件代表一个普通目录或文件名，`"."`， 或者`".."`。 

普通名称的意思是“进入这个目录或文件”。 

组件`"."`意思是“留在当前目录中”，所以它不会改变任何东西。 

组件`".."`意思是“移动到父目录”。 

任务是简化路径，使得最终结果不包含`"."`或者`".."`成分。 如果在某个时刻路径尝试移动到根目录之上，则该路径无效，我们必须打印`-1`。 

路径长度最多为 1000 个字符，非常小。 即使二次解也可能顺利通过，但问题的结构自然会导致线性时间解。 由于每个路径组件都是独立处理的，并且只影响当前目录堆栈，因此我们可以从左到右一次解决问题。 

危险情况与性能无关，而是与正确解释特殊组件有关。 

考虑输入：```
/../../a
```第一个`".."`已经尝试离开根目录。 正确的输出是：```
-1
```粗心的实现可能会默默地忽略额外的`".."`操作并错误返回`/a`。 

另一个微妙的情况是区分`"."`和`".."`来自包含点的普通名称。 

例如：```
/.../..hidden/./x
```组件`"..."`和`"..hidden"`是普通名称，不是特殊命令。 正确的简化路径是：```
/.../..hidden/x
```仅检查组件是否包含点的有缺陷的实现会错误地将它们视为父目录操作。 

根目录本身也需要小心处理。```
/
```结果必须保持准确`/`。 通过盲目地连接组件来重建答案可能会意外地产生一个空字符串。 

## 方法

 暴力方法会反复搜索路径以查找出现的情况`"."`和`".."`，重写字符串，并继续，直到没有特殊组件剩余。 

例如，如果我们看到`/a/b/../c`，我们可以将其重写为`/a/c`。 如果我们看到`/./`，我们将其删除。 该方法在概念上很简单，因为它直接模拟字符串本身的路径简化。 

问题是每次重写都会移动字符串中的字符。 如果路径包含许多嵌套目录和许多`".."`操作，每次重写都会花费线性时间，并且我们可能会执行线性多次重写。 路径长度为`n`，这可以退化为`O(n²)`运营。 

关键的观察结果是路径规范化仅取决于当前活动的目录组件的顺序。 当我们输入一个目录时，我们将其附加到当前路径。 当我们遇到`".."`，我们删除最新的目录。 这种行为就是一个堆栈。 

这将问题从“重复重写​​字符串”转变为“从左到右处理组件一次”。 

对于每个组件：

 如果是的话`"."`，我们忽略它。 

如果是的话`".."`，我们从堆栈中弹出一个目录。 如果堆栈已经为空，则路径无效。 

否则，该组件是一个普通名称，因此我们将其压入堆栈。 

最后，堆栈已按顺序包含规范路径组件。 我们只需加入他们`/`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 已被接受但效率低下 |
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 以字符串形式读取输入路径。 
2. 分割路径`/`。 

由于路径总是以`/`，第一个分割组件将是一个空字符串。 我们只是在处理过程中忽略空组件。 
3. 创建一个空堆栈。 

堆栈表示从根目录到当前目录的当前规范路径。 
4. 从左到右处理每个组件。 

这与浏览文件系统的真实行为相匹配。 
5. 如果组件为空或`"."`，跳过它。 

出现空组件是因为路径开头为`/`。 组件`"."`意思是“留在这里”，所以它没有改变任何东西。 
6. 如果该组件是`".."`，尝试从堆栈中删除最后一个目录。 

如果堆栈为空，则我们已经位于根目录，因此不可能向上移动。 打印`-1`并停止。 
7. 否则，该组件是普通目录或文件名。 

将其推入堆栈。 
8. 处理完所有组件后，重建规范路径。 

如果堆栈为空，则规范路径很简单`/`。 

否则，将所有堆栈元素连接起来`/`并在前面添加一个前导斜杠。 

### 为什么它有效

 处理完第一条后`k`组件，堆栈始终代表与这些组件相对应的确切规范路径`k`成分。 

推送普通名称匹配进入目录。 突然出现`".."`匹配返回父目录。 忽略`"."`匹配留在同一目录中。 

因为每个操作都完全按照文件系统语义的要求更新堆栈，所以最终的堆栈状态是路径的唯一规范版本。 唯一无效的情况是尝试从空堆栈中弹出，这恰好对应于在根目录上方移动。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    path = input().strip()

    stack = []

    for part in path.split('/'):
        if part == '' or part == '.':
            continue

        if part == '..':
            if not stack:
                print(-1)
                return
            stack.pop()
        else:
            stack.append(part)

    if not stack:
        print('/')
    else:
        print('/' + '/'.join(stack))

solve()
```该解决方案直接遵循基于堆栈的模拟。 

致电给`split('/')`将路径转换为单独的组件。 因为输入路径总是以`/`，第一个组件变为空字符串。 我们忽略这些组件。 

堆栈存储当前活动的目录。 每个普通的名字都被附加。 每一个`".."`删除最新的目录。 

最重要的实现细节是在调用之前检查堆栈是否为空`pop()`。 忘记此检查可能会崩溃或错误地允许在根目录之上移动。 

另一个微妙之处是重构最终答案。 如果堆栈变空，则正确的规范路径是`/`，不是空字符串。 这种特殊情况必须单独处理。 

条件：```
if part == '' or part == '.':
```也很重要。 仅精确匹配`"."`和`".."`很特别。 字符串像`"..."`或者`"..a"`必须保留普通路径名。

 ## 边缘情况

 考虑无效向上遍历的情况：```
/../../a
```该算法从空堆栈开始。 第一个组件是`".."`。 由于堆栈是空的，因此没有可返回的父目录。 该算法立即打印`-1`。 

这与文件系统语义完全匹配。 忽略此操作将错误地允许根目录之外的路径。 

现在考虑包含点的名称：```
/.../..hidden/./x
```其组成部分是：```
"...", "..hidden", ".", "x"
```该算法仅处理精确匹配`"."`和`".."`作为特别的。 所以`"..."`和`"..hidden"`通常被压入堆栈。 这`"."`组件被忽略，并且`"x"`已附加。 

最终堆栈变为：```
["...", "..hidden", "x"]
```其重构为：```
/../..hidden/x
```最后，考虑一条完全折叠回根的路径：```
/a/b/../..
```堆栈演变为：```
["a"]
["a", "b"]
["a"]
[]
```最后，栈是空的。 算法打印`/`而不是空字符串，这是根目录的正确规范表示。
