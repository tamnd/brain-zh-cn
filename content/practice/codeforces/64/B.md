 ## 解决方案
 ## 问题理解

 输入是一个写成三字符字符串的微小算术表达式。 第一个和第三个字符是来自的数字`0`到`9`，中间的字符是`+`或者`-`。 任务是计算表达式并打印结果整数。 

例如，输入`1-5`代表减法`1 - 5`，所以正确的输出是`-4`。 输入`7+2`代表`7 + 2`，所以输出是`9`。 

约束非常小，因为表达式始终具有固定长度。 不需要解析库、标记化、递归或表达式树。 恒定的工作量就足够了，因为我们只需要读取三个字符并应用一个算术运算。 

唯一微妙的部分是当结果变为负数时正确处理减法。 假设所有输出均为非负的粗心实现将在以下输入上失败：```
1-5
```正确的输出是：```
-4
```另一个容易犯的错误是在对字符进行操作之前忘记将其转换为整数。 例如，如果有人直接减去字符代码，结果将毫无意义。 有输入：```
9-2
```我们必须计算整数减法`9 - 2 = 7`，而不是 ASCII 值之间的差异。 

第三个边缘情况为零。 表达式如：```
0-0
```必须正确产生：```
0
```一些有缺陷的实现意外地进行了特殊情况的减法并错误地处理了相等的操作数。 

## 方法

 最直接的方法是检查操作员的性格并相应地计算结果。 由于表达式长度始终为三，因此我们可以通过索引访问第一个数字、运算符和第二个数字。 将数字字符转换为整数后，我们可以进行加法或减法。 

即使是暴力式解决方案，这里的时间实际上也是恒定的。 人们可以手动检查所有可能的表达式`0+0`通过`9-9`，将它们存储在查找表中，并打印匹配结果。 这仍然只涉及几百个操作，因为只有 200 个可能的表达式。 该方法是正确的，因为每个有效输入都属于这个有限集，但它不必要地僵化且可读性较差。 

更清晰的观察是输入已经直接编码了所有内容。 中间的字符完全决定了要应用哪种算术运算。 一旦我们将这两个数字转换为整数，计算就变成了一次加法或减法。

 ## 算法演练

 1. 读取输入字符串。 

表达式始终具有以下形式`digit operator digit`，因此其长度固定为三个字符。 
2. 提取第一个数字、运算符和第二个数字。 

第一个数字位于索引处`0`, 索引处的运算符`1`，以及索引处的第二个数字`2`。 
3. 将数字字符转换为整数。 

字符的算术不正确，因此我们必须使用`int()`。 
4. 检查操作员。 

如果操作员是`+`，计算总和。 否则，计算差值。 
5. 打印结果。 

### 为什么它有效

 表达式格式保证恰好有一个运算符和两个单位数操作数。 该算法直接读取这三个分量并应用相应的算术规则。 由于加法和减法完全按照表达式中的定义实现，因此生成的值始终与数学结果匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()

a = int(s[0])
op = s[1]
b = int(s[2])

if op == '+':
    print(a + b)
else:
    print(a - b)
```该程序首先读取表达式字符串并删除尾随的换行符`strip()`。 

第一个和第三个字符立即转换为整数。 这样就避免了直接对字符进行操作而导致的错误。 中间的字符存储为运算符。 

条件检查操作符是否是`'+'`。 如果为真，程序将打印总和。 否则，唯一剩下的有效运算符是`'-'`，所以它打印减法结果。 

不存在边界问题，因为输入格式保证表达式中恰好有三个字符。 Python 整数也可以安全地处理负值，所以像这样的情况`1-5`自然地工作。

## 测试用例```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    s = input().strip()

    a = int(s[0])
    op = s[1]
    b = int(s[2])

    if op == '+':
        print(a + b)
    else:
        print(a - b)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    backup_stdout = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup_stdout
    return out.getvalue()

# provided sample
assert run("1-5\n") == "-4\n", "sample 1"

# custom cases
assert run("0+0\n") == "0\n", "minimum values"
assert run("9+9\n") == "18\n", "maximum addition result"
assert run("9-0\n") == "9\n", "subtraction with zero"
assert run("0-9\n") == "-9\n", "negative result boundary"
assert run("5-5\n") == "0\n", "equal operands"

 ## 边缘情况

 考虑输入：```
1-5
```该算法提取`a = 1`,`op = '-'`， 和`b = 5`。 由于运算符是减法，在计算机中`1 - 5 = -4`。 输出是：```
-4
```这证实了无需任何特殊逻辑即可正确处理负值。 

现在考虑：```
0-0
```提取的值是`a = 0`,`op = '-'`， 和`b = 0`。 计算变为`0 - 0 = 0`，所以算法打印：```
0
```此案例验证了当两个操作数相等时减法不会意外引入符号错误。 

最后，考虑：```
9+9
```算法读取`a = 9`,`op = '+'`， 和`b = 9`。 由于运算符是加法，因此它计算`9 + 9 = 18`。 输出变为：```
18
```这表明即使两个操作数都是单位数，结果也不限于单位数。
