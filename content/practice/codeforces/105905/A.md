 ## 解决方案
 ## 问题理解

 该问题描述了一组参议员。 每个参议员都有一个强度值和当前的忠诚度百分比。 在投票开始之前，我们可能会分发有限数量的糖果。 给予参议员的每一颗糖果都会使该参议员的忠诚度提高 10%，但没有人能超过 100%。 分配后，每位参议员根据他们最终的忠诚概率独立投票支持或反对我们。 

如果超过半数的参议员投我们的票，我们就立即成功。 否则，我们可以尝试准确地清除那些投票反对我们的参议员。 罢免一个团体的机会取决于我们自己的实力以及被罢免的参议员的总实力。 我们需要选择最大化最终成功概率的糖果分配。 

参议员人数很少，这改变了整个策略。 由于最多有 8 名参议员，最终可能的忠诚度配置总数是可以管理的。 迭代参议员子集的解决方案是现实的，而为更大的群体尝试每种可能的投票结果的解决方案则无法扩展。 

糖果的数量也很少。 由于每种糖果仅将忠诚度值改变 10%，因此我们可以将决策表示为分配少量离散升级。 对每种可能的糖果分布的简单模拟是可能的，因为输入的大小很小。 如果参议员的数量在 10^5 左右，即使是线性通过也将是唯一合理的方向，指数枚举将立即失败。 

一些边缘情况很容易被忽略。 如果参议员已经有100%的忠诚度，给他们更多的糖果没有任何效果。 例如：```
1 3 20
20 100
```正确的输出是：```
1.0000000000
```盲目地将每一颗糖果都视为增加忠诚度的粗心实施可能会导致不可能超过 100% 的概率。 

当我们没有获得足够的选票并且必须依靠消除对手时，就会出现另一个极端情况。 例如：```
1 0 10
20 0
```唯一的参议员总是投票反对我们。 我们以概率删除该参议员：```
10 / (10 + 20) = 1 / 3
```所以答案是：```
0.3333333333
```仅检查我们是否可以获得多数选票的解决方案将错误地返回零。 

## 方法

 第一种方法是直接尝试所有糖果发行版。 由于每颗糖果都分配给其中一位参议员，因此我们可以递归地选择每颗糖果的去向。 生成一个分布后，我们计算新的忠诚度并评估获胜的概率。 

这种方法是正确的，因为所有可能的花费糖果的方式都被考虑到了。 对于每个分布，可以通过迭代所有可能的投票掩码来计算概率。 对于 n 位参议员，有 2^n 种可能的投票结果。 对于每个面具，我们都会确定它是否已经给了我们足够的积极票。 如果没有，我们计算罢免所有落选参议员的概率。 

问题是糖果分发的数量增长很快。 如果我们有 k 个糖果和 n 个参议员，则分配的数量大约为 n^k。 即使只有 8 名参议员，增加 k 也会使这种方法变得昂贵。 总工作量约为 O(n^k * 2^n)，多次重复相同的投票计算。 

关键的观察是糖果只会影响每个参议员的最终忠诚度。 我们不关心给予糖果的确切顺序。 参议员们的最终状态就足够了。 由于 n 和 k 都非常小，因此我们可以使用动态规划来代替糖果的使用。 

我们一颗一颗地处理糖果并存储所有可达到的忠诚度状态。 一个州由每位参议员在分发一些糖果后的忠诚度来表示。 可能的状态数量是有限的，因为每个参议员只有 11 个可能的忠诚度值：0、10、20，最多 100。分配完所有糖果后，我们评估每个可达状态并保留最佳概率。 

过渡很简单。 从目前的状态来看，任何尚未达到 100% 状态的参议员都可以再获得一颗糖果。 新状态将添加到下一层。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^k * 2^n * n) | O(n) | 对于较大的 k 来说太慢 |
 | 最佳 | O(k * S * n + S * 2^n * n) | O(S)| 已接受 |

 这里S是可达忠诚度状态的数量。 当 n = 8 时，最大可能的状态数足够小。 

## 算法演练

 1. 读取参议员并将每个忠诚度百分比转换为代表 10% 区块数量的整数。 70 的忠诚度变为 7。这使得糖果操作变得简单，因为一颗糖果只需添加一颗即可。 
2. 从包含初始忠诚度值且不使用糖果的单一状态开始。 这是我们做出任何选择之前唯一可能的情况。 
3. 对于每种糖果，创建所有可能的新状态。 从当前的每个州开始，尝试向忠诚度仍低于 100% 的每位参议员发放糖果。 将该参议员的忠诚度增加一个区块并存储结果状态。 
4. 处理完所有糖果后，检查每个最终的忠诚度状态。 对于每个状态，通过迭代所有可能的投票掩码来计算成功的概率。 如果一个掩码给了我们多数，那么它的概率就会直接做出贡献。 否则，计算罢免每位失败参议员的概率并添加该贡献。 
5. 取所有最终状态的最大概率。 这就是答案，因为每种可能的糖果分配都会导致其中一种生成状态。 

为什么有效：动态规划准确地保留了影响未来决策的信息。 糖果唯一改变的是每个参议员当前的忠诚度，因此达到相同忠诚度向量的两个不同历史具有相同的未来可能性。 评估步骤检查每个可能的投票结果，这意味着它计算最终状态的确切成功概率。 由于生成了每种可能的最终状态，因此其中的最大值就是最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    first = input().split()
    if not first:
        return
    n, k, A = map(int, first)

    senators = []
    for _ in range(n):
        b, l = map(int, input().split())
        senators.append((b, l // 10))

    start = tuple(x[1] for x in senators)
    states = {start}

    for _ in range(k):
        nxt = set()
        for state in states:
            for i in range(n):
                if state[i] < 10:
                    arr = list(state)
                    arr[i] += 1
                    nxt.add(tuple(arr))
        states = nxt

    total_masks = 1 << n
    answer = 0.0

    for state in states:
        cur = 0.0
        for mask in range(total_masks):
            prob = 1.0
            bad_sum = 0
            good = 0

            for i in range(n):
                p = state[i] / 10.0
                if mask & (1 << i):
                    good += 1
                    prob *= p
                else:
                    prob *= (1.0 - p)
                    bad_sum += senators[i][0]

            if good > n // 2:
                cur += prob
            else:
                cur += prob * (A / (A + bad_sum))

        if cur > answer:
            answer = cur

    print("{:.10f}".format(answer))

if __name__ == "__main__":
    solve()
```代码的第一部分以百分之十为单位存储每个参议员的忠诚度。 这避免了状态生成阶段期间的浮点变化。 该集合名为`states`包含使用加工过的糖果后可以达到的所有忠诚度向量。 

转换循环遵循第三个算法步骤。 忠诚度值为 10 的参议员已经代表了 100%，因此增加它会创建一个无效状态。 这是动态规划中的主要边界条件。 

评估循环会检查投票赞成的参议员的每个可能子集。 位掩码告诉我们哪些参议员投票给了我们。 我们将独立投票概率相乘即可得到确切结果的概率。 当结果不是多数时，代码会计算失败参议员的实力并应用去除概率。 

表达式`A / (A + bad_sum)`使用浮点除法计算。 这些值足够小，Python 的浮点精度足以满足所需的输出。

 | 时间 | O(k * S * n + S * 2^n * n) | 我们通过糖果转换生成状态并评估每个最终状态 |
 | 空间| O(S)| 我们只存储当前层的忠诚度状态 |

 参议员的数量最多为 8 名，因此即使迭代所有投票掩码也很便宜。 可达到的忠诚度状态的数量也受到少量忠诚度级别和糖果的限制，因此该解决方案很容易满足预期的限制。

import sys
import io

def solve(data):
    sys.stdin = io.StringIO(data)
    input = sys.stdin.readline

    first = input().split()
    n, k, A = map(int, first)

    senators = []
    for _ in range(n):
        b, l = map(int, input().split())
        senators.append((b, l // 10))

    states = {tuple(x[1] for x in senators)}

    for _ in range(k):
        nxt = set()
        for state in states:
            for i in range(n):
                if state[i] < 10:
                    arr = list(state)
                    arr[i] += 1
                    nxt.add(tuple(arr))
        states = nxt

    ans = 0.0
    for state in states:
        cur = 0.0
        for mask in range(1 << n):
            p = 1.0
            bad = 0
            good = 0
            for i in range(n):
                if mask >> i & 1:
                    good += 1
                    p *= state[i] / 10.0
                else:
                    p *= 1.0 - state[i] / 10.0
                    bad += senators[i][0]
            if good > n // 2:
                cur += p
            else:
                cur += p * A / (A + bad)
        ans = max(ans, cur)

    return f"{ans:.10f}\n"

 ## 边缘情况

 当参议员已经拥有最大忠诚度时，过渡必须忽略该参议员。 对于输入：```
1 3 20
20 100
```唯一生成的状态仍然是忠诚度 10。投票概率是 1，因此答案恰好是 1。算法会处理这个问题，因为状态永远不会创建为忠诚度高于 10 的状态。 

当没有人支持我们，我们必须依靠清除时，评估阶段仍然有效。 为了：```
1 0 10
20 0
```唯一的投票面具是失败的选票。 参议员的强度为 20，因此移除机会为 10 / 30。算法将投票概率乘以该值并返回 0.3333333333。 

当糖果在多个参议员之间分配时，不同的订单可以创建相同的最终忠诚向量。 状态集删除了这些重复项，因此算法不会浪费时间重新计算相同的情况。 这是使动态规划方法高效的属性。
