 ## 解决方案
 ## 问题理解

 我们有两个描述鼓事件的字符串。 第一个字符串`p`是实际的击打顺序：每个字符都是左鼓上的一次击打（`L`）或右鼓（`R`）。 第二串`s`是所听到的。 单次点击并不总是在录音中创建单个字符：`L`hit 可以显示为`L`或者`LL`，和一个`R`hit 可以显示为`R`或者`RR`。 

任务是判断记录的字符串是否`s`可能是从命中序列中产生的`p`。 

输入包含多个测试用例。 对于每种情况，整个输入中所有字符串的长度都足够大，以至于重复搜索或回溯的解决方案不适合。 总长度约为`2 * 10^5`，我们需要一个线性或近线性算法。 任何二次方都会围绕`4 * 10^10`最坏情况下的操作，这远远超出了正常的 Codeforces 时间限制所允许的。 

棘手的部分是可以拉伸相同的连续字符。 粗心的解决方案可能只会检查是否`p`是一个子序列`s`，但这忽略了分组规则。 例如，如果`p = "LR"`和`s = "LLLR"`，子序列检查成功，因为我们可以发现`L`和`R`，但答案实际上是`NO`。 第一击最多可以创建两个`L`字符，所以三个`L`之前的字符`R`不能来自同一个原始点击。 

另一种边缘情况是字符数正确但组错误。 为了`p = "LL"`和`s = "L"`，输出是`NO`。 中的每个角色`p`代表一个单独的点击，因此两个点击都必须出现在录音中。 仅比较最终字母计数的解决方案可能会错误地接受这一点。 

最终的边界情况是单个字符。 为了`p = "R"`和`s = "RR"`，输出是`YES`因为一击可以发出两次声音。 为了`p = "RR"`和`s = "R"`，输出是`NO`因为两声敲击不能缩成一声。 

## 方法

 直接的方法是模拟所有可能的扩展`p`。 每个字符有两个选择，所以一个长度的字符串`n`可以生产多达`2^n`可能的录音。 这是正确的，因为它会尝试所有有效的转换，但即使对于中等长度，它也会变得毫无用处。 和`n = 200000`，可能性的数量是无法枚举的。 

问题的结构给了我们一个更小的视角。 中的连续相等字符`p`必须对应于一个连续的相同字符块`s`。 如果我们将两个字符串分成最大块，则每个块`p`可以独立增长一倍或两倍。 一块长度`x`在`p`可以成为一个长度的块`x`或者`2x`在`s`。 

这一观察消除了尝试选择的需要。 我们只需要比较两个字符串的压缩形式。 如果对应块的字母不同，则无法进行转换。 如果一个块来自`s`比匹配块短`p`，这是不可能的，因为声音无法消失。 如果它长于原始块的两倍，则不可能，因为每次命中最多贡献两个副本。 

蛮力之所以有效，是因为每个有效答案都是原始字符串的扩展，但会失败，因为它探索了许多等效的可能性。 块比较之所以有效，是因为块内的所有字符都具有相同的行为，因此唯一重要的信息是块长度。

 ## 算法演练

 1. 将两个字符串分成相等的连续字符组。 例如，`"LLLRR"`变成块`("L", 3)`和`("R", 2)`。 这些块代表彼此相邻出现的相同鼓类型的单独击打。 
2. 比较两个字符串中的块数。 如果不同，则立即给出答案`NO`。 中的每个块`p`必须与其中的一个块完全匹配`s`，因为唯一允许的更改是重复相同的字符。 
3. 对于每对匹配块，检查它们的字符是否相等。 左击不能变成右音，右击不能变成左音。 
4. 比较每对木块的长度。 如果录制的块长度小于原始块长度，则录音丢失且无效。 如果它大于原始长度的两倍，则可用命中的声音过多。 否则该块有效。 
5. 如果每个块都通过了检查，则打印`YES`。 

这样做的原因是压缩准确地保留了与转换相关的信息。 在一个块内，每个原始打击都是同一类型的鼓打击。 唯一可能的更改是添加一个额外的副本，因此整个块只能缩放一到两倍之间。 不同的块不能合并或拆分，因为这会改变击鼓的顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def compress(s):
    res = []
    i = 0
    n = len(s)
    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1
        res.append((s[i], j - i))
        i = j
    return res

def solve():
    t = int(input())
    ans = []
    for _ in range(t):
        p = input().strip()
        s = input().strip()

        a = compress(p)
        b = compress(s)

        if len(a) != len(b):
            ans.append("NO")
            continue

        ok = True
        for (c1, x), (c2, y) in zip(a, b):
            if c1 != c2 or y < x or y > 2 * x:
                ok = False
                break

        ans.append("YES" if ok else "NO")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```这`compress`函数遍历字符串一次并构建连续的块。 它使用两个指针：`i`标记块的开始并且`j`移动直到角色发生变化。 这避免了重复切片并保持总工作的线性。 

主循环首先比较块的数量。 这可以捕获块边界丢失的情况，例如原始块边界`"LR"`试图成为`"LRL"`。 之后，检查配对的块。 条件`y > 2 * x`是最常见的差一错误的地方，因为块允许加倍，但不能更多。 

Python 整数在这里不会溢出，因为唯一的算术涉及字符串长度，最多几十万。

 ## 边缘情况

 对于`p = "LR"`和`s = "LLLR"`，压缩给出`(L,1),(R,1)`和`(L,3),(R,1)`。 第一对失败，因为记录的长度大于原始长度的两倍。 算法返回`NO`，避免治疗错误`p`作为子序列。 

为了`p = "LL"`和`s = "L"`，压缩形式是`(L,2)`和`(L,1)`。 第二根弦太短，因为两次单独的敲击需要产生至少两个声音。 长度比较立即发现了这一点。 

为了`p = "R"`和`s = "RR"`，块是`(R,1)`和`(R,2)`。 记录的大小正是允许的最大值，因此算法接受它。 这验证了上边界条件。 

为了`p = "LR"`和`s = "LRL"`，第二个字符串的压缩形式有三个块，而第一个字符串有两个。 由于单个原始块无法分割成不同鼓的另一个块，因此算法在进行任何长度检查之前会拒绝它。
