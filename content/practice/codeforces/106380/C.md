 ## 解决方案
 ## 问题理解

 我们得到一个有向图，其中每条边都带有颜色标签。 该图中的步行允许重新访问顶点和边，但只有当沿步行的颜色严格交替时，它才变得“有效”，这意味着您永远不允许遍历相同颜色的两个连续边。 

任务是确定使用这样的有效步行可以从节点 1 到达哪些顶点。 对于在此约束下可以到达的每个顶点，我们将其包含在输出中。 

关键点是可达性不仅取决于当前节点，还取决于最后使用的边的颜色。 仅跟踪节点的幼稚可达性概念是不够的，因为以不同的最后边缘颜色到达同一节点会导致不同的未来可能性。 

所有测试用例的输入大小总共允许多达一百万个节点和边。 这立即排除了任何尝试显式枚举所有路径的解决方案。 即使将所有状态存储在路径上的朴素 BFS 中也会爆炸，因为由于循环和重复重访，可能的行走数量呈指数增长。 

当相同颜色的多个边缘形成循环时，会出现微妙的边缘情况。 例如，考虑完全由颜色 1 的边连接的节点链。从节点 1，您可以到达节点 2，但无法使用另一条颜色 1 的边从节点 2 继续。 忽略颜色约束的幼稚 BFS 会错误地标记所有可到达的节点，而正确的答案取决于遵守交替规则。 

另一个极端情况是通过多个不同颜色的传入边可到达的节点。 例如，如果可以通过节点 2 的红色边缘以及节点 4 的蓝色边缘到达节点 3，则从节点 3 开始的下一个转换取决于我们考虑的到达。 将这些状态折叠成每个节点的单个访问标志会失去正确性。 

## 方法

 一个简单的想法是在路径上执行 BFS 或 DFS。 每个状态将代表当前节点和最后使用的边缘颜色。 从一个状态开始，我们尝试所有颜色与最后一个颜色不同的传出边缘。 这是正确的，因为它直接编码问题约束。 然而，如果简单地实现，这很快就会变得低效，因为可以使用不同的传入颜色多次重新访问同一节点，并且图形可能包含许多边。 

关键的观察是，如果我们正确构造状态空间，状态空间实际上并不大。 我们不需要探索任意路径，而只需要考虑形式对（节点，最后一个颜色）。 每个边沿转换都会在恒定时间内更新此状态。 由于每条边都会被处理有限次数，因此我们可以将其视为扩展状态图上的图遍历。 

然而，即使这样也可以进一步优化。 我们可以观察到过渡仅取决于最后的边缘颜色，而不是完整的历史记录，而不是显式扩展所有颜色状态。 这建议维护按颜色分组的邻接列表并执行携带最后使用的颜色的 BFS。 每个兼容的传入状态都会有效地考虑每条边一次。 

蛮力思想之所以有效，是因为它探索了所有有效的行走，但由于重复重新计算相同的状态转换而失败。 优化的视图将所有路径历史压缩到一个小的状态图中，其中每个有意义的区别只是最后使用的颜色。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 路径上的 DFS/BFS（无状态压缩）| 指数| O(n + m) | 太慢了|
 | BFS over（节点，最后一种颜色）状态 | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

1. 构建邻接表，其中每个条目都存储邻居和边缘颜色。 这种表示允许我们在遍历期间根据颜色兼容性过滤过渡。 
2. 将 BFS 状态定义为 (node, last_color) 对。 last_color 开始时是一个特殊值，表示“没有前一条边”，允许从节点 1 开始的第一次移动使用任何颜色。 
3. 初始化状态为 (1, none) 的队列。 我们还维护一个以（node，last_color）为键的访问结构，这样我们就不会重新处理相同的状态。 
4. 从队列中弹出一个状态 (v, c_prev)。 对于每条出边 (v → to, c)，我们仅当 c 与 c_prev 不同时才考虑它。 这会在每一步中局部强制执行交替颜色条件。 
5. 如果我们到达一个新状态 (to, c)，则将其标记为已访问并将其推入队列。 每一个这样的转变都代表着一段有效的多彩行走的延伸。 
6. BFS 完成后，收集在任何状态下到达的所有节点，无论最后的颜色如何。 这些节点正是通过至少一次有效的彩色步行可到达的节点。 

关键思想是我们永远不会合并最后颜色不同的状态，因为这种区别会影响未来的转换。 一旦 BFS 稳定，每个可达状态都代表某种交替颜色行走的有效前缀。 

### 为什么它有效

 BFS 探索一个图，其节点用最后边缘颜色信息进行增强。 每个转换都保留了以下不变式：存储的状态对应于来自节点 1 的有效交替颜色行走。由于每个有效行走都可以分解为此类转换的序列，因此原始图中的每个可到达顶点必须出现在至少一个可到达状态中。 相反，BFS 产生的每个状态都对应于有效的构造遍历，因为我们只沿着颜色与前一个不同的边缘延伸。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque, defaultdict

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        
        g = [[] for _ in range(n + 1)]
        for _ in range(m):
            u, v, c = map(int, input().split())
            g[u].append((v, c))
        
        # BFS over (node, last_color)
        # last_color = 0 means "no previous edge"
        q = deque()
        q.append((1, 0))
        
        visited = set()
        visited.add((1, 0))
        
        reachable = set([1])
        
        while q:
            v, pc = q.popleft()
            for to, c in g[v]:
                if c == pc:
                    continue
                state = (to, c)
                if state not in visited:
                    visited.add(state)
                    reachable.add(to)
                    q.append(state)
        
        print(*sorted(reachable))

if __name__ == "__main__":
    solve()
```邻接列表存储有向边及其颜色，允许对传出转换进行恒定时间迭代。 BFS 队列存储完整的状态信息，以便在本地强制执行颜色约束。 

一个常见的实现陷阱是忘记初始状态必须允许任何颜色。 这就是为什么初始的last_color设置为零，这样可以保证不匹配任何真实的边缘颜色。 

另一个微妙的问题是访问的结构。 仅将节点标记为已访问会错误地修剪有效状态，因为到达具有不同最后颜色的节点可能会启用新的转换。

 ## 边缘情况

 关键的边缘情况是一个线性链，其中所有边缘共享相同的颜色。 在这种情况下，只有节点 1 的第一步有效，并且后续的每个转换都会被阻止。 BFS 正确地停止扩展，因为任何重用相同颜色的尝试都会立即违反状态条件，因此永远不会添加第一跳之外的节点。 

另一个边缘情况是当一个节点可以通过具有不同最后颜色的多条路径到达时。 该算法正确地独立地保留了两种状态，因此未来的转换不会被过早地丢弃。 例如，如果通过红色边缘和蓝色边缘到达节点 2，则状态 (2，红色) 和 (2，蓝色) 都保持活动状态，从而启用仅节点访问的数组将错过的不同传出扩展。
