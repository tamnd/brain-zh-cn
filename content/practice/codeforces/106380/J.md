 ## 解决方案
 ## 问题理解

 该问题描述了具有一组固定实验的课程注册系统。 学生们一一到达并选择一个实验。 第一个选择实验的学生在该实验中接收索引 1，下一个学生接收索引 2，依此类推。 之后，两个已经分配的位置可以交换占用它们的学生，即使这些位置属于不同的实验。 毕竟，我们需要按递增的索引顺序打印当前占据其位置的学生的每个实验。 

输入包含实验和事件的数量。 类型 1 的事件将新的学生 ID 附加到一个实验的末尾，从而在那里创建下一个可用索引。 类型 2 的事件仅通过交换存储的学生 ID 来更改两个选定的位置。 输出必须保留每个实验的位置的内部顺序。 

约束是数据结构选择的关键。 最多可以有$3 \times 10^5$实验和$3 \times 10^5$事件，因此通过移动整个实验列表来模拟交换会太慢。 单个实验可能包含许多学生，因此我们需要对一个实验的大小进行对数运算。 存储的学生总数最多为类型1事件的数量，也是$3 \times 10^5$，因此每个学生一个节点的数据结构是可行的。 

主要的边缘情况来自于实验指标是独立的这一事实。 

考虑一个学生加入一个空实验。```
Input
2 1
1 2 100000001
```事件结束后，实验 2 包含一名学生。 输出必须包含带有该学生 ID 的索引 1。 如果不小心将实验编号视为学生位置，可能会错误地放置学生。 

另一个棘手的情况是在不同大小的不同实验中交换相同的位置。```
Input
3 3
1 1 100000001
1 1 100000002
1 2 100000003
2 1 2 2 1
```交换之前，实验1是`[100000001, 100000002]`实验2是`[100000003]`。 交换实验 1 的第二个位置与实验 2 的第一个位置，实验 1 为`[100000001, 100000003]`实验 2 为`[100000002]`。 交换整个实验而不是位置的解决方案会产生错误的结果。 

最后一个边缘案例是一个从来不接待学生的实验。```
Input
3 0
```所有三个输出行必须仅包含零。 假设每个实验至少有一个存储值的代码将在此处失败。 

## 方法

 直接方法会将每个实验存储为正常列表。 添加学生很容易，最终输出也很容易。 难度为2类事件。 要交换两个位置，我们需要访问每个列表内的任意索引。 如果我们使用链表，访问索引将花费线性时间。 如果我们使用普通数组，访问速度很快，但是使用动态数组和许多插入的实验总数需要仔细管理。 更重要的是，搜索所有事件并重建受影响的实验数据的暴力思想可以达到$O(m^2)$，这是周围$9 \times 10^{10}$最坏情况下的操作。 

使问题易于管理的观察结果是，每个实验只需要三个操作：在后面追加、读取一个位置和写入一个位置。 我们从不插入到中间或删除元素。 这意味着每个实验都可以由支持随机访问的动态序列来表示。 

隐式陷阱是很自然的选择。 它将序列顺序存储在树结构中，而不是存储显式索引。 每个子树的大小让我们能够在对数时间内找到包含第 k 个元素的节点。 追加只是将当前的treap 与新的单节点treap 合并。 交换两个位置变成两个第 k 个查询，后面跟着两个赋值。 

蛮力方法之所以有效，是因为它正确地模拟了最终的排列，但它失败了，因为重复随机访问和大型序列的移动成本太高。 隐式trap保持相同的序列行为，同时将每个事件减少为对数工作。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(m^2)$|$O(m)$| 太慢了|
 | 最佳|$O(m \log m)$|$O(m)$| 已接受 |

 ## 算法演练

 1. 为每个实验创建一个空的隐式trap root。 每个节点代表一个学号，并存储其子树的大小，以便快速找到位置。 
2. 当学生选择实验时，创建一个包含该学生 ID 的新 treap 节点，并将其合并到实验当前 treap 的右侧。 这会将学生置于下一个可用索引处。 
3. 当出现交换事件时，使用子树大小将节点定位在第一个请求的位置。 以同样的方式找到第二个请求位置的节点。 只交换他们存储的学生证。 
4. 处理完所有事件后，对每个实验的trap 进行有序遍历。 遍历顺序与原始索引顺序相同，因此收集到的ID已经按实验索引排序。 

为什么它有效：隐式trap保持的不变性是它的有序遍历正是该实验中的位置序列。 追加会保留此顺序，因为新节点在末尾合并。 交换仅更改存储在两个位置的值，因此序列顺序保持不变。 由于最终遍历按升序访问每个位置，因此生成的名册与所需的输出匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

left = [0]
right = [0]
size = [0]
value = [0]
priority = [0]

seed = 123456789

def rng():
    global seed
    seed ^= seed << 7
    seed ^= seed >> 9
    return seed & 0xFFFFFFFF

def new_node(v):
    value.append(v)
    priority.append(rng())
    left.append(0)
    right.append(0)
    size.append(1)
    return len(value) - 1

def pull(x):
    size[x] = size[left[x]] + size[right[x]] + 1

def merge(a, b):
    if not a:
        return b
    if not b:
        return a
    if priority[a] > priority[b]:
        right[a] = merge(right[a], b)
        pull(a)
        return a
    else:
        left[b] = merge(a, left[b])
        pull(b)
        return b

def kth(x, k):
    while True:
        lsz = size[left[x]]
        if k == lsz + 1:
            return x
        if k <= lsz:
            x = left[x]
        else:
            k -= lsz + 1
            x = right[x]

def collect(x, out):
    if x:
        collect(left[x], out)
        out.append(value[x])
        collect(right[x], out)

def solve():
    n, m = map(int, input().split())
    roots = [0] * (n + 1)

    for _ in range(m):
        event = list(map(int, input().split()))
        if event[0] == 1:
            _, i, x = event
            roots[i] = merge(roots[i], new_node(x))
        else:
            _, i1, j1, i2, j2 = event
            a = kth(roots[i1], j1)
            b = kth(roots[i2], j2)
            value[a], value[b] = value[b], value[a]

    ans = []
    for i in range(1, n + 1):
        cur = []
        collect(roots[i], cur)
        if cur:
            ans.append(str(len(cur)) + " " + " ".join(map(str, cur)))
        else:
            ans.append("0")
    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```数组`left`,`right`,`size`， 和`value`全局存储trap节点。 使用数组代替对象可以减少Python内存开销，因为学生总数可以达到$3 \times 10^5$。 

这`merge`函数仅用于追加，因为新学生总是在实验结束时加入。 随机优先级使陷阱保持平衡，因此其高度以高概率保持对数。 

这`kth`函数是迭代的，以避免在最频繁的随机访问操作期间不必要的递归。 它使用左子树的大小来决定目标位置是在左子树内部、当前节点还是在右子树内部。 

最终的遍历使用中序顺序，因为隐式trap不存储显式索引。 合并期间树的形状会发生变化，但有序序列始终保持实验顺序。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(m \log m)$| 除了所有存储的学生的最终线性遍历之外，每个追加、位置查找和最终遍历步骤都需要对数时间。 |
 | 空间|$O(m+n)$| 我们为每个实验存储一个根，为每个学生存储一个trap 节点。 |

 ## 边缘情况

 对于空实验，算法将其根保持为零。 在最终遍历期间，零根产生一个空列表，因此输出行仅包含`0`。 在trap逻辑中没有特殊情况，因为空序列是自然表示的。 

为了在不同规模的实验之间进行交换，两个调用`kth`在自己的陷阱中独立搜索。 例如，如果实验 1 有`[1,2]`实验2有`[3]`，将实验 1 的位置 2 与实验 2 的位置 1 交换，将存储的值更改为`[1,3]`和`[2]`。 树结构不会移动，因此所有其他索引保持不变。 

对于单个学生的实验，`kth`收到`k = 1`。 左子树大小为零，因此它立即返回该节点。 这可以避免在最小有效索引处出现相差一的错误。
