 ## 解决方案
 ## 问题理解

 我们有两堆公正的游戏。 一个位置由两个堆大小表示，例如`(x, y)`。 在一轮中，玩家可以从一堆石子中取出任意正数的石子。 他们还可以从两个堆中移除正数，但是两个移除的数量最多必须相差`k`。 没有合法动作的玩家就输了，所以`(0, 0)`是一个亏损的位置。 

对于每个最多`10^5`独立游戏，我们收到两个初始桩尺寸和公差`k`。 我们需要打印`2`恰好在第一个玩家的起始位置失败时，并且`1`否则。 官方声明确认了这些界限和样本数据。 

大坐标范围，`x,y <= 10^9`，排除任何按堆大小索引的动态规划。 即使一款游戏也可能包含大约`10^18`不同的立场。 和`10^5`游戏和 2 秒限制，预期的解决方案必须在每场游戏中使用恒定或对数的算术量。 事实是`k <= 12`这也强烈暗示公差以受控方式改变结构，而不需要对可能的公差进行大量搜索。 

有几种边缘情况很容易被错误处理。 

终端位置比较特殊。 用于输入```
1
0 0 0
```正确的输出是```
2
```因为第一个玩家没有动作。 仅处理正索引并意外地将索引零视为普通 P 位置的公式可能会出错。 

这些桩是可以互换的，因此输入坐标的顺序一定不重要。 为了```
1
2 1 0
```正确的输出是`2`， 因为`(1,2)`是一个亏损的 Wythoff 位置。 假设第一个坐标总是较小而不实际交换值的实现可能会拒绝有效的 P 位置。 

公差会改变相关的对角线间距。 为了```
1
1 3 1
```正确的输出是`2`。 该位置正在亏损，因为它是广义 Wythoff 位置之一`k=1`。 将条件视为`|a-b| < k`而不是`|a-b| <= k`改变游戏并给出错误的分类。 

桩差不能被整除的情况`k+1`也具有重要意义。 为了```
1
1 2 1
```正确的输出是`1`。 这里的区别是`1`， 尽管`k+1=2`，因此该位置本身不能是解描述的 P 位置之一。 如果粗心的实现只检查差异是否“小”而不是它是否与所需的算术级数匹配，则会对其进行错误分类。 

最后，牌堆相等并不意味着某个位置会输。 为了```
1
5 5 3
```正确的输出是`1`。 本场比赛中唯一平等的P位是`(0,0)`，因为只要指数为正，广义 P 位置就有正差异。 

## 方法

 最直接的方法是递归地解决博弈。 如果每一步合法的棋步都走向了获胜的位置，则该位置是失败的；如果至少有一个棋步走向了失败的位置，则该位置是获胜的。 通过记忆，这给出了正确的动态程序。 

问题在于状态空间的大小。 如果初始桩是`X`和`Y`，记忆可能仍然需要每个位置`(x,y)`和`0 <= x <= X`和`0 <= y <= Y`。 那大约是`XY`州。 即使我们只计算单桩移动，在所有状态上检查的转换总数是

 \frac{XY(X+Y+2)}2。 
]

为了`X=Y=10^9`，这是关于`10^27`在考虑两堆移动之前先进行过渡。 没有记忆的递归更糟糕，因为它反复探索相同的子游戏。 

突破在于不再单独考虑每个头寸，而是准确描述哪些头寸正在亏损。 该博弈是 Wythoff Nim 的广义形式。 对于正整数`r = k+1`，其 P 位由下式生成

 [
 a_n=\left\lfloor n\alpha\right\rfloor,
 \qquad
 b_n=a_n+rn,
 ]

 哪里

 [
 \alpha=\frac{2-r+\sqrt{r^2+4}}2.
 ]

 这是标准的广义 Wythoff 结构，其中两个互补的 Beatty 序列的不同之处在于`rn`。 相应的 P 位表征也称为`k`-Wythoff Nim 表征。 

原因`r=k+1`显得特别干净。 连续P位有差异

 [
 b_n-a_n=rn。 
]

 如果我们尝试从 P 位置移动`n`到较早的 P 位置`m`，两个移除的量相差

 [
 rn-rm=r(n-m)。 
]

自从`r=k+1`，这个差值至少是`k+1`，所以这样的移动违反了允许的界限`k`。 P 位置之间不可能进行单桩移动，因为坐标序列是互补的。 

互补属性是解决方案的另一半。 序列`(a_n)`和`(b_n)`每个正整数恰好包含一次。 这是 Beatty 定理的直接结果，因为两个斜率满足

 [
 \frac1\alpha+\frac1{\alpha+r}=1。 
]

 这为我们提供了一种方法来证明每个非 P 位置都有一个移动到 P 位置的过程。 

最后的分类就特别简单了。 将两堆排序，以便`x <= y`， 让`d=y-x`，并把`r=k+1`。 如果`d`可以整除`r`, 让

 [
 n=\frac d r.
 ]

 仓位正在丢失的时候

 [
 x=a_n。 
]

 否则就是赢了。 

还剩下一个数字问题。 计算`floor(n*alpha)`直接使用浮点是有风险的，因为`n`可以大到`10^9`。 我们可以完全删除浮点数。 自从

 \左\l地板
 \frac{n(2-r)+n\sqrt{r^2+4}}2
 \右\r地板，
 ]

 让

 [
 q=\left\lfloor n\sqrt{r^2+4}\right\rfloor。 
]

 然后

 [
 q=\left\lfloor\sqrt{n^2(r^2+4)}\right\rfloor,
 ]

 可以用Python精确计算`math.isqrt`。 因此

 [
 a_n=
 \frac{n(2-r)+q}{2}
 ]

 具有整数楼层除法。 不需要浮点近似。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(XY(X+Y))`每场比赛都有记忆|`O(XY)`| 太慢了|
 | 最佳|`O(log(x+y))`每局算术 |`O(1)`| 已接受 |

 ## 算法演练

 1. 对于每个游戏，首先对牌堆重新排序，以便`x <= y`。 游戏是对称的，因此这不会改变其结果。 
2. 设置`r = k + 1`。 广义 Wythoff P 位置具有以下形式`(a_n,b_n)`与

 [
 b_n-a_n=rn。 
]

 因此，一个位置只能是 P 位置，如果`y-x`可以整除`r`。 
3.如果`d = y-x`不能被整除`r`，立即将该位置归类为获胜。 P位确实有区别`rn`对于某个整数`n`。 
4. 否则计算`n = d // r`。 具有这种差异的唯一可能的 P 位置是`(a_n,b_n)`，所以剩下的问题是是否`x`等于`a_n`。 
5. 计算

 [
 a_n=
 \左\l地板
 n\frac{2-r+\sqrt{r^2+4}}2
 \right\rfloor
 ]

 without floating point. Calculate

 [
 q=\运算符名{isqrt}(n^2(r^2+4)),
 ]

 then use

 [
 a_n=(n(2-r)+q)//2.
 ]

这`isqrt`运算给出平方根的精确整数下限。 
6. 如果`x == a_n`，该位置是 P 位置，因此第一个玩家输了，我们打印`2`。 Otherwise it is an N-position, so the first player wins and we print`1`。 

### 为什么它有效

 两个序列

 [
 a_n=\lfloor n\alpha\rfloor,
 \qquad
 b_n=\lfloor n(\alpha+r)\rfloor
 ]

 是互补的，因为它们的斜率满足

 [
 \frac1\alpha+\frac1{\alpha+r}=1。 
]

 Consequently, every positive integer appears in exactly one of the two sequences.

 考虑两个带有索引的不同 P 位置`m < n`。 它们的坐标差均为正，两个去除量之差为

 k+1。 
]

 因此，任何合法的两堆移动都不能连接两个 P 位置。 一堆移动也无法将它们连接起来，因为互补性意味着不同 P 位置坐标之间不共享坐标。 

现在采取非P位置`(x,y)`和`x <= y`。 如果一个坐标属于上一序列`b_n`，互补性让我们可以通过单桩移动减少另一个坐标以获得相应的 P 位置。 

剩下的情况是`x=a_m`和`y=a_n`。 如果`y>b_m`，我们可以减少`y`到`b_m`并达到`(a_m,b_m)`。 否则，

 [
 d=y-x=a_n-a_m<b_m-a_m=rm。 
]

 选择

 [
 j=\left\lfloor\frac d r\right\rfloor。 
]

然后`j<m`和

 [
 0\le d-rj\le r-1=k。 
]

自从`a_j < a_m=x`和`b_j=a_j+rj <= y`，我们可以将两堆都减少到`(a_j,b_j)`。 两个移除的量完全不同`d-rj`，这最多是`k`。 因此，每个非 P 位置都可以移动到 P 位置。 

这两个属性正是失败位置的定义属性：没有任何动作离开 P 位置，而其他所有位置都有移动进入 P 位置。 因此分类是正确的。 

## Python 解决方案```python
import sys
import math

input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        x, y, k = map(int, input().split())

        if x > y:
            x, y = y, x

        r = k + 1
        d = y - x

        if d % r != 0:
            out.append("1")
            continue

        n = d // r

        # a_n = floor(n * (2 - r + sqrt(r^2 + 4)) / 2)
        # floor(n * sqrt(D)) = isqrt(n^2 * D)
        D = r * r + 4
        q = math.isqrt(n * n * D)

        a = (n * (2 - r) + q) // 2

        if x == a:
            out.append("2")
        else:
            out.append("1")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```循环的第一部分对两个堆进行排序。 这让其余代码可以使用约定`x <= y`并避免检查每个 P 位置的两个方向。 

变量`r`是`k+1`， 不是`k`。 这种一对一的关系是游戏的核心细节。 P 位置差是以下倍数`k+1`，因为两个 P 位置之间的距离必须大于允许的差异`k`删除的金额之间。 

可整性测试在任何平方根计算之前进行。 如果`d`不能被整除`r`，没有可能存在具有该坐标差的 P 位置，因此答案立即`1`。 

什么时候`d`是可除的，`n=d/r`确定唯一的候选 P 位置。 然后代码计算其较小的坐标`a_n`。 

表达式涉及`isqrt`是准确的。 让`D=r*r+4`。 自从

 [
 \operatorname{isqrt}(n^2D)=\lfloor n\sqrt D\rfloor,
 ]

 我们可以用整数代替 Beatty 公式的无理数部分。 Python 整数具有任意精度，因此最大的中间值约为`10^20`，不能溢出。 

这`// 2`尽管存在不合理的术语，操作也是安全的。 如果

 [
 n\sqrt D=q+f,\qquad 0\le f<1,
 ]

 那么被限制的数量是`(integer + f)/2`。 无论整数部分是偶数还是奇数，小数部分永远不能将结果推过下一个整数。 因此，下限是通过整数分子精确获得的：`// 2`。 

代码使用`sys.stdin.readline`按要求。 每个游戏仅需要少量整数运算和一个整数平方根，该实现就可以轻松避免构建任何大型游戏状态表。

 考虑第一个示例游戏，`(0,0,k=0)`。 这里`r=1`并且这些堆已经被订购了。

现在考虑示例游戏`(23,9,k=1)`。 重新排序给出`(9,23)`。 自从`r=k+1=2`，差异是`14`，所以候选索引是`n=7`。

 [
 a n=\floor n\sqrt 2\rfloor。 
]
在`n=7`,
 [
 a_7=\floor 7\sqrt 2\floor=9。 
]
 |`x`|`y`|`k`|`r`|`d`|`n=d/r`|`a_n`|`x == a_n`| 结果 |
 | ---| ---| ---| ---| ---| ---| ---| ---| ---|

对于公差边界附近的非 P 位置，请考虑`(1,13,k=12)`。 这里`r=13`，而差异正是`12`，小于`r`。 

|`x`|`y`|`k`|`r`|`d`|`d % r`|`n`|`a_n`| 结果 |

 差值不能被整除`13`，所以这不能是 P 位置。 事实上，第一个玩家可以删除`1`从第一堆石头中取出`13`从第二个开始，达到`(0,0)`。 这两个金额完全不同`12`，所以此举是合法的。

 ## 边缘情况

 对于终端位置```
1
0 0 0
```算法得到`r=1`,`d=0`， 和`n=0`。 精确的平方根表达式为零，所以`a_0=0`。 自从`x=0`，该位置被识别为失败，输出为`2`。 实际上不需要特殊情况`(0,0)`。 

对于反转坐标，请考虑```
1
2 1 0
```算法首先交换桩并得到`(1,2)`。 和`r=1`，差异是`1`, 给予`n=1`。 公式给出`a_1=1`，所以位置为P，答案为`2`。 如果没有初始交换，正确的 P 位置可能会被拒绝，因为它的坐标是以相反的顺序提供的。 

对于公差边界，请考虑```
1
1 13 12
```这里`r=13`和`d=12`。 自从`12 % 13 != 0`，算法立即返回`1`。 这是正确的，因为广义 P 位置存在差异`0,13,26,39,...`。 该位置实际上是通过直接移动来获胜的`(1,13)`到`(0,0)`，这会删除`1`和`13`石头，其差异恰好是允许的公差`12`。 

对于具有相同公差的实际 P 位置，请考虑```
1
1 14 12
```现在`d=13`， 所以`n=1`。 和`r=13`,

 [
 a_1=
 \左\l地板
 \frac{2-13+\sqrt{173}}2
 \右\r地板
 =1。 
]

因此`(1,14)`是一个 P 位置，输出是`2`。 这对准确地证明了相关间距的原因`k+1`，而不是`k`。 

对于相等的桩，请考虑```
1
5 5 3
```差异为零，所以`n=0`和`a_0=0`。 由于较小的堆是`5`， 不是`0`，位置不是P，答案是`1`。 第一个玩家可以从一堆石头中取出五块石头并到达`(0,5)`，之后对手有一步棋。 

对于最大坐标，请考虑```
1
1000000000 1000000000 12
```再次`d=0`，所以只有`n=0`需要考虑。 该算法计算`a_0=0`，看到堆大小不为零，并打印`1`。 大坐标永远不会导致状态空间爆炸，因为解决方案不会枚举任何位置。 

最后一个微妙的情况是精确的浮点边界。 该公式包含一个无理数平方根乘以一个大的指数`10^9`。 使用`float`并打电话`int(n*alpha)`理论上，如果舍入到整数的错误一侧，可能会导致答案错误。 该实现通过将不合理的计算替换为`math.isqrt(n*n*(r*r+4))`，因此每次比较都是使用精确的整数进行的。
