 ## 解决方案
 ## 问题理解

 我们有一排`n`灯笼，确切地说`k`其中一些已开启，并且`4 <= k <= n <= 100`。 我们可以向法官询问灯笼的任何子集。 如果该子集包含`x`灯笼点亮，法官不透露`x`。 相反，它返回的除数数`x`是复合的。 

让`F(x)`表示该响应。 例如，`F(4) = 1`，因为唯一的合因子`4`是`4`本身。 还，`F(3) = 0`， 因为`3`是素数。 

任务是准确确定哪个`k`灯笼亮着，最多使用`2 * 10^5`查询。 

的小值`n`是具有欺骗性的。 可以有`C(100, 4) = 3,921,225`不同的四个灯笼子集，因此测试每个四个灯笼子集已经太昂贵了。 同时，`n <= 100`意味着二次或立方数量的查询可以容纳在限制内，因为`C(100, 3) = 161,700`。 

主要的困难在于`F(x)`不是一对一的。 例如，`F(25) = F(26) = 1`， 因为`25`有合数因数`{25}`和`26`有合数除数`{26}`。 假设答案唯一决定点亮灯笼数量的策略将默默地失败。 

还有一个关于价值的边界问题`4`。 我们有`F(3) = 0`但`F(4) = 1`，这使得 4 特别有用。 例如，如果`n = 4, k = 4`，查询所有四个灯笼给出`1`，而任何最多包含三个点亮的灯笼的子集给出`0`。 基于普通二分查找的方法不能简单地将法官的响应视为隐藏计数。 

提供的示例是交互式的，因此其显示的回复不构成普通的输入/输出测试用例。 样本的`0`回复是来自原始交互记录的响应，而不是批处理程序可以独立重现的数据。 

## 方法

 一种直接的方法是查询每个四元素子集。 四元素子集包含零到四个点亮的灯笼。 在这些可能性中，只有`x = 4`有一个非零答案，因为`0`,`1`,`2`， 和`3`没有与此相互作用相关的复合因子。 因此，对四个灯笼的查询返回`1`就在所有四个灯笼都亮起来的时候。 

一旦每个四子集都被测试过，灯笼就会在它属于至少一个正四子集时准确地亮起。 这是正确的，因为`k >= 4`，因此每个点亮的灯笼都可以与其他三个点亮的灯笼配对。 

问题是查询计数。 在最坏的情况下，这会执行`C(100, 4) = 3,921,225`查询次数，远远超出了限制`200,000`。 

关键的观察结果是，我们实际上不需要查询恰好包含四个灯笼的子集。 我们可以从整排灯笼中移走一小组灯笼。 

假设我们选择一个集合`T`的`t`灯笼并查询除以下灯笼之外的所有灯笼`T`。 如果`r`里面有灯笼`T`打开，查询的集合恰好包含`k - r`点燃了灯笼。 答案是`F(k-r)`。 

现在选择最小的正值`t`这样`F(k-t) != F(k)`。 

对于这个问题的约束条件，检查`t = 1, 2, 3`对每个人来说都足够了`k`从`4`通过`100`。 这是允许范围内的有限属性，因此可以在预计算时进行验证`F`。 这里相关的最长等距离长度为三。 

选择_最小_这样的`t`这使得查询变得有用。 对于每一个`r < t`, 极小性给出`F(k-r) = F(k)`。 

为了`r = t`，根据定义，`F(k-t) != F(k)`。 

a 的查询补集`t`-元素集最多可以包含`t`排除点燃的灯笼。 因此它的响应不同于`F(k)`恰好在什么时候`r = t`，这意味着当每个灯笼在`T`已开启。 

我们已经将神秘的除数响应转换为干净的除数响应`t`-方式和测试。 自从`t <= 3`，我们可以测试所有可能的`t`-元素集。 最坏的情况是所有三元素子集，仅`161,700`查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`O(n^4)`查询 |`O(n)`| 太慢了|
 | 最佳|`O(n^3)`查询 |`O(n)`| 已接受 |

 构建每个查询的实际计算工作是`O(n)`，所以产出建设总量为`O(n^4)`最坏情况下的字符操作，但是判断查询的数量，也就是这里的绑定约束，最多是`C(100,3) = 161,700`。 

## 算法演练

 1. 预计算`F(x)`，每个的合因数的数量`x`从`1`通过`100`。 如果`x = p_1^{a_1} ... p_m^{a_m}`，它的约数总数是`(a_1 + 1) ... (a_m + 1)`。 其中，一是`1`确切地说`m`是素数，所以`F(x) = tau(x) - m - 1`。 
2. 阅读`n`和`k`，然后找到最小的`t`在`{1, 2, 3}`为此`F(k-t)`不同于`F(k)`。 约束条件`k >= 4`保证所有这些指数均为正值。 
3. 考虑候选集`T`正是`t`灯笼。 询问补数`T`，这意味着除以下灯笼外的所有灯笼都包括在内`T`。 
4.让`r`是点亮灯笼的数量`T`。 查询的补体包含`k-r`灯笼亮了，法官回来了`F(k-r)`。 
5.如果`r < t`，最小选择`t`给出`F(k-r) = F(k)`。 如果`r = t`, 所有灯笼`T`亮起，响应为`F(k-t)`，这不同于`F(k)`。 自从`r`不能超过`t`，响应不同于`F(k)`正是在每一个灯笼出现的时候`T`已开启。 
6. 枚举每一个`t`-元素子集`T`。 每当它的补集产生不同于`F(k)`，标记每个灯笼`T`如点燃。 
7. 尽快停止`k`灯笼已被标记。 每一个有标记的灯笼都是真正点燃的，因为有确切的`k`点亮灯笼，完整的标记集就是答案。 

### 为什么它有效

 不变量是a`t`-当所有元素集都从其补集查询中接收到不同的响应时`t`灯笼亮了。 对于包含少于`t`点亮的灯笼，补充包含其中之一`k, k-1, ..., k-(t-1)`点亮的灯笼，所有这些值都有相同的响应`k`根据最小的定义`t`。 如果全部`t`灯笼点亮，补语包含`k-t`点亮灯笼并产生不同的反应。 

因为`t <= 3`尽管`k >= 4`，每个点亮的灯笼至少属于一个`t`-完全由点亮的灯笼组成的元素子集。 这样的子集将被检测到并标记该灯笼。 相反，没有未点亮的灯笼可以属于检测到的子集，因为检测到的子集必须完全由点亮的灯笼组成。 因此，标记的集合正是点亮的灯笼的集合。 

## Python 解决方案

 下面的程序是实际的交互解决方案。 它读取初始`n`和`k`，立即打印每个查询，读取法官的响应，最后打印恢复的配置。```python
import sys
from itertools import combinations

input = sys.stdin.readline

def composite_divisor_count(x):
    if x <= 1:
        return 0

    divisors = 0
    for d in range(2, x + 1):
        if x % d != 0:
            continue

        # d is composite iff it has a divisor other than 1 and itself.
        composite = False
        for q in range(2, int(d ** 0.5) + 1):
            if d % q == 0:
                composite = True
                break

        if composite:
            divisors += 1

    return divisors

def main():
    n, k = map(int, input().split())

    f = [0] * (k + 1)
    for x in range(1, k + 1):
        f[x] = composite_divisor_count(x)

    base = f[k]

    t = -1
    for candidate in range(1, 4):
        if f[k - candidate] != base:
            t = candidate
            break

    # This is guaranteed by the constraints of the problem.
    if t == -1:
        return

    answer = [False] * n
    found = 0

    for excluded in combinations(range(n), t):
        query = ['1'] * n
        for i in excluded:
            query[i] = '0'

        print("? " + ''.join(query), flush=True)

        response = int(input())
        if response == -1:
            return

        if response != base:
            for i in excluded:
                if not answer[i]:
                    answer[i] = True
                    found += 1

            if found == k:
                break

    result = ''.join('1' if x else '0' for x in answer)
    print("! " + result, flush=True)

if __name__ == "__main__":
    main()
```这`composite_divisor_count`最多仅针对数字调用函数`100`，所以它的简单试除法已经足够快了。 更面向公式的实现可以使用除数计数和不同质因数的数量，但直接版本的含义是`F(x)`明确的。 

该程序存储`F(k)`在`base`。 寻找`t`故意开始于`1`，因为使用尽可能小的`t`就是保证每一个较小数量的被排除的点亮的灯笼都会产生与全套灯笼相同的答案。 

对于每个组合，查询都被初始化为所有`'1'`字符和选定的`t`位置更改为`'0'`。 这是候选集的补充，这是必不可少的。 查询候选人本身会产生`r`而不是`k-r`，并且极小性论证将不再适用。 

响应仅与`base`。 我们不需要知道查询中点亮的灯笼的确切数量。 不同的反应足以得出结论：所有`t`排除的灯笼都亮了。 

该代码还处理法官的`-1`根据交互协议的要求立即响应。 

Python 中不存在整数溢出问题。 最大组合数仅为`161,700`，并且字符串的长度最多`100`。

import itertools

def composite_divisor_count(x):
    if x <= 1:
        return 0

    ans = 0
    for d in range(2, x + 1):
        if x % d != 0:
            continue

        composite = False
        for q in range(2, int(d ** 0.5) + 1):
            if d % q == 0:
                composite = True
                break

        if composite:
            ans += 1

    return ans

def solve_offline(n, hidden):
    k = sum(hidden)

    f = [0] * (k + 1)
    for x in range(1, k + 1):
        f[x] = composite_divisor_count(x)

    base = f[k]

    t = None
    for candidate in range(1, 4):
        if f[k - candidate] != base:
            t = candidate
            break

    assert t is not None

    answer = [False] * n

    for excluded in itertools.combinations(range(n), t):
        r = sum(hidden[i] for i in excluded)
        response = f[k - r]

        if response != base:
            for i in excluded:
                answer[i] = True

        if sum(answer) == k:
            break

    return ''.join('1' if x else '0' for x in answer)

# Provided sample parameters, using a concrete hidden configuration.
assert solve_offline(
    9,
    [1, 0, 1, 1, 0, 0, 1, 0, 1]
) == "101100101"

# Minimum-size instance: every lantern is on.
assert solve_offline(
    4,
    [1, 1, 1, 1]
) == "1111"

# k = 5, where t = 1.
assert solve_offline(

    [1, 0, 1, 0, 1, 0, 0, 1]
) == "10101001"

 ## 边缘情况

 第一个重要的边缘情况是`n = k = 4`。 唯一可能的配置是`1111`。 这里`F(4) = 1`尽管`F(3) = 0`，所以算法选择`t = 1`。 排除任何灯笼，正好留下三个点亮的灯笼并产生`0`，与基本响应不同`1`。 每个灯笼都被标记，给出`1111`。 

第二种边缘情况是重复的除数计数响应。 拿`k = 26`。 我们有`F(26) = 1`和`F(25) = 1`，因此测试单个灯笼的互补不会透露任何信息。 算法继续`t = 2`， 在哪里`F(24) = 5`，不同于`F(26)`。 对于一对被排除的灯笼，这对叶子中零个或一个点亮的灯笼`25`或者`26`查询中点亮的灯笼，都产生`1`。 仅当两个排除的灯笼都点亮时，查询才包含`24`点燃灯笼并返回`5`。 因此，该对充当精确的双灯 AND 测试。 

第三个边缘情况是`k = 34`。 这里`F(34) = F(33) = 1`，因此单灯补码再次失败。 但`F(32) = 4`, 给予`t = 2`。 该算法测试每一对并准确检测由两个点亮的灯笼组成的对。 自从`k = 34`比两个大得多，每个点亮的灯笼都属于许多这样的对，所以它们都被找到了。 

第四个边缘情况是`k = 35`。 值满足`F(35) = F(34) = F(33) = 1`，所以第一个差异出现在`t = 3`， 和`F(32) = 4`。 这是最糟糕的查询计数情况，因为可能必须检查所有三元素子集。 只有`C(100,3) = 161,700`这样的子集即使当`n = 100`，仍低于`200,000`限制。 对于任何包含少于三个点亮的灯笼的三子集，查询的补集包含`35`,`34`， 或者`33`点燃灯笼并返回`1`。 包含三片点亮的灯笼叶子的三子集`32`点燃灯笼并返回`4`，因此准确地检测到所需的子集。 

最后，当所有`n`灯笼亮起，每个查询的排除集都完全点亮。 第一个不同`t`仍然仅由`k`，第一个检测到的子集立即标记其成员。 算法一旦全部停止`k`位置已经被标记，因此在这种情况下不需要穷尽所有可能的查询。
