 ## 解决方案
 ## 问题理解

 给定一个数组，我们使用它的前缀和。 让`pref[i]`表示第一个的总和`i`元素，与`pref[0] = 0`。 一个子数组`[l, r]`当其总和为零时称为良好，相当于`pref[r] - pref[l-1] = 0`， 或者`pref[r] = pref[l-1]`。 

然后，这个问题要求我们计算一个更强的概念：如果一个子数组包含至少一个总和为零的子子数组，那么它就是好-好。 就前缀和而言，这意味着在范围内`[l-1, r]`，必须存在两个索引`i < j`这样`pref[i] = pref[j]`。 如果所有前缀总和为`[l-1, r]`不同，则不存在零和子数组，并且该段被认为是坏-好。 

所以任务简化为计算子数组`[l, r]`使得前缀总和为`[l-1, r]`并不都是截然不同的。 

输入是一个整数数组，我们必须计算这种“好-好”子数组的数量。 

如果数组大小达到大约`10^5`，子数组的任何二次枚举都变得不可能。 一个天真的`O(n^2)`扫描已经产生周围`5 * 10^9`操作，速度太慢。 这立即表明我们需要线性或近线性扫描，很​​可能使用滑动窗口。 

当所有前缀和全局不同时，就会出现微妙的边缘情况。 例如，如果数组严格增加正数，例如`[1, 2, 3]`，那么每个前缀和都是不同的，因此任何地方都不存在零和子数组。 正确答案应该是`0`。 仅检查本地子数组而不跟踪前缀唯一性的简单方法会错误地计算许多段。 

另一种边缘情况是数组有许多重复的前缀和。 例如`[1, -1, 1, -1]`产生重复的前缀和和许多零和子数组。 这里，正确的计数取决于检测第一个重复边界，而不是枚举子数组。 

## 方法

 暴力策略修复`(l, r)`并检查是否存在重复的前缀和`[l-1, r]`。 这需要扫描段或每个查询使用一组。 每张支票都是`O(n)`，并且有`O(n^2)`段，给予`O(n^3)`或者`O(n^2 log n)`取决于实施。 这太慢了。 

关键的观察是翻转条件。 我们不直接计算好片段，而是考虑补集：所有前缀和都不同的片段。 这些正是不包含重复前缀和的段，这意味着它们内部不存在零和子数组。 

我们可以修复正确的端点`r`并保持最长的有效段结束于`r`使得前缀和是唯一的。 让`l`是最小的索引，使得`[l, r]`无效，意思是里面有重复的前缀和`[l, r]`。 那么所有的起点`l' < l`产生有效段`[l', r]`都很好，而且全部`l' >= l`产生无效的。 

因此，对于每个`r`，贡献正好是`l`，我们可以使用滑动窗口和哈希图来计算它，该哈希图跟踪最后一次出现的前缀和。

 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(n) | 太慢了|
 | 最优滑动窗口 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们首先将数组转换为前缀和，因为问题完全是关于前缀值的相等性。 

然后我们在前缀索引上维护一个滑动窗口`[l, r]`这样里面的所有前缀和都是不同的。 

1. 初始化哈希图`last`，它存储看到每个前缀和的最后一个索引。 还设置了`l = 0`和`answer = 0`。 
2. 迭代`r`从`0`到`n`超过前缀和。 每一步都试图扩展窗口以包括`pref[r]`。 
3.如果`pref[r]`之前曾在该位置见过`p`， 和`p >= l`，那么我们必须移动`l`到`p + 1`。 这是必要的，因为保持`p`窗口内会引入重复的前缀和，从而违反唯一性。 
4.固定后`l`，我们添加贡献`l`到答案。 这计算了有多少个起点产生了一个以好坏为结尾的段`r`，对应于原始公式中的良好段。 
5. 更新`last[pref[r]] = r`。 

我们使用前缀索引而不是数组索引的原因是子数组和被编码为两个前缀位置之间的相等性。 

### 为什么它有效

 在任何固定的`r`, 窗户`[l, r]`是最长的后缀`r`所有前缀和都不同。 任意起点`l' < l`确保`[l', r]`必须包含重复的前缀和，因为重复出现在`l-1`并且一些较早的位置被强制在该段内。 反之，任意`l' >= l`使段内的所有前缀和保持不同。 这会创建有效和无效起点的干净分区，使得`l`准确的贡献边界。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    last = {}
    l = 0
    ans = 0

    for r in range(n + 1):
        x = pref[r]

        if x in last and last[x] >= l:
            l = last[x] + 1

        last[x] = r
        ans += l

    print(ans)

if __name__ == "__main__":
    solve()
```该实现直接遵循前缀和上的滑动窗口思想。 关键的细节是我们迭代`pref[0..n]`，不是原始数组。 地图`last`存储前缀和的位置，以及指针`l`总是向前跳跃，从不向后跳跃，确保线性复杂性。 

积累`ans += l`对应于计算以每个结尾的子数组的所有有效起始位置`r`。

 ## 边缘情况

 当所有元素都为零时，每个前缀和在每一步都会重复。 该算法开始于`l = 0`，以及每个新的`0`力量`l`跳转到最后一次出现的位置加一。 这创造了最大的转变并产生随着增长而增长的贡献`0 + 1 + 2 + 3`。 

当所有前缀和不同时，哈希映射永远不会触发重置`l`。 窗口保持最大，但由于不存在重复的前缀和，因此每个段在包含零和子数组方面都是无效的，导致贡献为零。 

当单个值重复相距很远时，例如前缀和`[0, 5, 10, 5, 15]`，跳入`l`正好发生在第二个时`5`出现。 指针立即跳过所有无效的开始，这是防止二次行为的关键机制。
