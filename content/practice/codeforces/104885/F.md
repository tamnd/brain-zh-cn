 ## 问题理解

 我们得到了大小的排列$n$和一组范围查询。 每个查询由一个间隔定义$[l, r]$。 任务是为每个查询计算一个取决于索引对的值$(i, j)$使得一个索引在排列排序条件的意义上“划分”另一个索引$p_i \mid p_j$在声明上下文中给出。 

关键的困难在于这些有效对并不独立于查询。 取决于是否$i$和$j$落在查询间隔之内或之外，它们的贡献要么影响答案，要么抵消。 因此，我们不是简单地计算全局除数关系，而是仅计算那些交互完全包含在查询段中的对。 

输入由排列和多个范围查询组成。 对于每个查询，我们必须输出与该区间完全相关的有效除数对的数量。 

这些约束意味着不可能对每个查询进行简单的重新计算。 所有指数中相关对的数量就像除数上的调和级数一样增长，因此对的总数为$O(n \log n)$，但是当两个查询都执行任何二次方操作时，都会立即失败$n$并且查询量很大。 

对于每个查询，一种简单的暴力方法将迭代所有对$(i, j)$，检查整除条件，并验证两个端点是否位于区间内。 这是正确的，但太慢了，因为它变成了$O(n^2)$最坏情况下的每个查询。 

一个更微妙的失败案例来自于尝试在不考虑间隔边界的情况下预先计算全局计数。 例如，如果我们预先计算所有有效对一次，我们就会对查询中只有一个端点的对进行计数，并且除非我们仔细构建贡献，否则没有直接的减法。 

## 方法

 主要思想是分离对如何与查询间隔交互。 对于每对$(i, j)$，恰好存在三种可能性：两个索引都位于区间之外，恰好有一个位于区间之内，或者两者都位于区间之内。 只有最后一类才有助于回答。 

暴力方法显式检查每个查询的每一对，并按区间成员资格进行过滤。 这很快就变得不可行。 

关键的观察是我们可以将问题转化为前缀后缀簿记问题。 我们不是重新计算每个查询的贡献，而是维护一个运行结构，该结构累积每个位置迄今为止看到的有效“除数命中”数量。 

我们定义一个辅助数组`count`， 在哪里`count[j]`代表有多少个索引$i$到目前为止看到满足整除关系$p_i \mid p_j$。 我们从左到右扫描索引，更新每个索引的贡献$i$成其在排列空间中的所有倍数。 

对于每个查询，我们将其答案分解为两个累积和：一个在左边界计算，一个在右边界计算。 该差异精确地隔离了完全包含在区间内的对，因为跨越边界的对对称抵消。 

这将问题转化为：

 维护多个点的更新并回答范围总和查询`count`。 该结构自然由 Fenwick 树或线段树处理。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2 \cdot q)$|$O(1)$| 太慢了|
 | 芬威克/扫线|$O(n \log^2 n + q \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 现在，我们使用扫描索引和 Fenwick 树来维护动态计数来逐步构建解决方案。 

### 1. 初始化 Fenwick 树$n$职位

 我们需要一个支持点更新和前缀和查询的结构。 这是必要的，因为每个索引$i$为多个职位做出贡献$j$，并且我们还需要查询边界的快速范围总和。 

### 2.扫一扫$i$从 1 到$n$在每个位置$i$，我们考虑所有位置$j$这样$p_i$划分$p_j$。 对于每一个这样的$j$，我们增加`count[j]`在 Fenwick 树中乘 1。 

这一步构建了处理索引后的不变量$i$，从指数到的所有除数贡献$i$都体现在`count`。 

### 3. 处理按右端点分组的查询

 我们将每个查询与其端点相关联。 当我们扫描时，当我们到达索引时$i$，我们还计算右边界为的所有查询的贡献$i$。 我们记录一个值`right_k`等于`count`超过$[l_k, r_k]$。 

这使用直到右边界的索引捕获所有贡献。 

### 4. 对左边界重复相同的逻辑

 我们从概念上重复扫描或维持第二次评估来计算`left_k`，它对应于完全包含左边界之前的贡献。 

区别`right_k - left_k`精确隔离两个指数均位于区间内的那些对。 

减法之所以有效，是因为跨越边界的每一对对两侧都有对称的贡献，而完全内部的对在`right_k`。 

### 为什么它有效

 正确性取决于对每个有效对的分类$(i, j)$根据它是否完全位于查询间隔之前、横跨查询间隔还是内部。 

完全外部的对不会影响任何一个前缀和。 跨越边界的对对两者的贡献相等`left_k`和`right_k`，所以它们抵消了。 仅对完全包含在$[l, r]$出现在`right_k`但不在`left_k`。 

这种不变性确保减法精确地分离出所需的计数，而不会重复计算或遗漏。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        if r < l:
            return 0
        return self.sum(r) - self.sum(l - 1)

def solve():
    n, q = map(int, input().split())
    p = list(map(int, input().split()))

    queries = [[] for _ in range(n + 1)]
    for idx in range(q):
        l, r = map(int, input().split())
        queries[r].append((l, idx))

    bit = Fenwick(n)
    count = [0] * (n + 1)

    right = [0] * q
    left = [0] * q

    for i in range(1, n + 1):
        val = p[i - 1]
        j = val
        while j <= n:
            bit.add(j, 1)
            j += val

        for l, idx in queries[i]:
            right[idx] = bit.range_sum(l, i)

    bit = Fenwick(n)

    for i in range(1, n + 1):
        val = p[i - 1]
        j = val
        while j <= n:
            bit.add(j, 1)
            j += val

        for l, idx in queries[i]:
            left[idx] = bit.range_sum(l, i)

    ans = [right[i] - left[i] for i in range(q)]
    print(*ans)

if __name__ == "__main__":
    solve()
```芬威克树用于维持进化`count`数组，其中每次更新都会将整除性的贡献从当前索引传播到所有相关倍数。 这`range_sum`查询计算查询间隔内有多少有效贡献。 

我们存储按右端点分组的查询，以便我们可以计算`right_k`恰好在扫描到达该端点时。 第二次相同的扫描用于`left_k`，减法隔离了内部对。 

一个微妙的实现细节是对倍数的迭代`j = val, 2*val, ...`，它有效地编码除数关系，而不是显式检查所有对。 

## 工作示例

 考虑一个小排列$p = [1, 2, 3, 4]$和两个查询$[1, 3]$和$[2, 4]$。 

### 第一次扫描（右值）

 | 我| 值| 更新 | BIT 状态（概念计数） | 已处理的查询 |
 | ---| ---| ---| ---| ---|
 | 1 | 1 | +1 在 1,2,3,4 | 所有的| 无 |
 | 2 | 2 | +1 在 2,4 | 增加至 2,4 | 查询 [1,3] 计算 |
 | 3 | 3 | +1 于 3 | 增加 3 | 查询 [2,4] 计算 |
 | 4 | 4 | 4 时+1 | 增加 4 | 无 |

 供查询$[1,3]$,`right`捕获最多 3 个指数的贡献。 

### 第二次扫描（左值）

 重新计算相同的过程，但在完全包含边界贡献之前有效地隔离前缀行为。 

这种差异消除了部分跨越边界的对，只留下完全内部的对。 

这演示了相同的扫描如何编码相同累积结构的不同边界解释。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(n \log^2 n + q \log n)$| 每个索引更新调和成本中的所有倍数，每个查询使用Fenwick范围查询|
 | 空间|$O(n + q)$| Fenwick 树和查询存储 |

 除数枚举的调和性质确保总更新受以下限制$O(n \log n)$，并且每个 Fenwick 运算都会贡献一个额外的对数因子。 这完全符合典型的限制$n, q \le 2 \cdot 10^5$。

 ## 边缘情况

 一个关键的边缘情况是当所有元素都是小除数时，例如$[1,2,3,4,5,\dots]$。 在这种情况下，每个索引都会对许多未来位置做出贡献，并且天真的每个查询重新计算将会爆炸。 基于扫描的 Fenwick 结构可以处理这个问题，因为每个贡献都通过谐波增长进行摊销。 

当查询覆盖整个范围时，会出现另一种边缘情况。 然后`left`和`right`对于跨越边界的许多对来说变得相同，并且减法仅留下完全内部的对。 该算法仍然有效，因为两次扫描都看到相同的更新历史记录。 

第三种情况是单元素查询$[i,i]$。 只有独立的对才会起作用，并且由于除数更新包括自整性，因此 Fenwick 结构正确地计算是否$p_i \mid p_i$，即使在单位间隔内也能确保一致的行为。
