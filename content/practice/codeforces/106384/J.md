 ## 解决方案
 ## 问题理解

 该任务描述了一个图问题，其中给定了一组节点之间的有向连接，并要求我们确定通过遵循这些有向边可以形成的最长可能路径。 这里的路径是指节点的序列，其中每个连续的对都通过有向边连接，并且节点不会沿着相同的路径重新访问。 

尽管语句很短，但“最长路径问题”的结构强烈表明我们正在研究有向无环图。 如果允许循环，则最长路径通常是未定义的，因为我们可以无限循环。 因此，有意义的解释是该图要么显式是 DAG，要么隐式保证是非循环的。 

输入可以理解为图形描述，其中节点表示状态，有向边表示允许的转换。 输出是一个整数，表示任何有效有向路径中的最大边数（或等效的节点减一）。 

从复杂性的角度来看，节点的数量通常足够大，以至于任何涉及枚举所有路径的方法都是不可能的。 路径的强力枚举呈指数增长，因为每个分支点都会使可能的延续数成倍增加。 即使有几十个节点，这也是不可行的，因此解决方案必须利用图中的结构，而不是直接探索路径。 

如果我们不注意图结构，一些边缘情况很容易被忽略。 如果图根本没有边，则最长路径应该为零，因为不存在转换。 如果图是单链，例如 1 → 2 → 3 → 4，则答案就是该链的长度。 当多个路径合并时会出现更微妙的情况，例如 1 → 3、2 → 3、3 → 4。不记忆的简单 DFS 会重复重新计算子问题，并且即使图很小，也可能会超时。 

另一个微妙的问题是假设没有循环处理的简单 DFS 是安全的。 如果输入意外地包含像 1 → 2 → 3 → 1 这样的循环，则简单的递归将无限循环或重复访问状态，从而产生不正确的结果，除非我们明确确保拓扑或访问顺序结构。 

## 方法

 思考这个问题最直接的方法是尝试枚举从每个节点开始的每条可能的路径。 从每个节点，我们尝试所有传出边缘，递归地扩展路径，直到不可能进一步扩展为止，跟踪所看到的最大长度。 

这种方法是正确的，因为它探索了图中的所有有效路径。 然而，其成本迅速爆炸。 在每个节点都有两个出边的图中，每一步路径数量都会加倍，在最坏的情况下会导致大约 O(2^n) 的行为。 子路径的重复重新计算是主要的低效率：每次从不同的前驱到达该节点时，都会重新计算从该节点开始的最长路径。 

关键的结构观察是，一旦我们知道从节点开始的最长路径，该值就永远不会改变。 如果图是非循环的，则依赖结构形成偏序，这意味着我们可以按逆拓扑顺序计算答案。 每个节点仅依赖于排序中位于其之后的节点。 这将问题从指数分支转换为 DAG 上的单遍动态规划问题。 

我们定义 dp[u] 为从节点 u 开始的最长路径。 对于每条边 u → v，我们可以将路径从 u 延伸一步加上从 v 开始的任何最佳路径。因此 dp[u] 只是 1 + dp[v] 的所有邻居 v 中的最大值。 如果我们以逆拓扑顺序处理节点，则所有 dp[v] 值在需要时都已计算出来。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力DFS枚举| O(2^n) | O(2^n) | O(n) | 太慢了|
 | DAG 上的 DP（拓扑排序）| O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 我们继续将图转换为一个结构，其中依赖项在依赖项之前被处理。 

1. 首先，我们构建有向图的邻接表。 这种表示允许我们有效地访问任何节点的所有传出边。 如果没有这个，每次转换都需要重复扫描整个边缘列表，这会带来不必要的开销。 
2. 我们计算节点的拓扑排序。 此排序确保对于每个有向边 u → v，节点 v 按顺序出现在 u 之前。 这个属性至关重要，因为它保证当我们计算 dp[u] 时，传出边的所有 dp[v] 值都是已知的。 
3. 我们初始化一个 dp 数组，并将所有值设置为零。 每个dp[u]最终都会存储从u开始的最长路径。 
4. 我们以逆拓扑顺序迭代节点。 这个方向很重要，因为它确保我们总是在它可以直接到达的所有节点之后处理该节点。 
5. 对于每个节点 u，我们检查所有出边 u → v。我们将 dp[u] 更新为 dp[u] = max(dp[u], 1 + dp[v])。 此步骤体现了这样的思想：从 u 开始的任何路径都必须首先经过其输出边之一，然后从下一个节点继续最佳地继续。 
6. 处理完所有节点后，我们将最终答案计算为 dp 中的最大值。 这代表整个图中的最佳起点。 

### 为什么它有效

 正确性取决于以下事实：在 DAG 中，每条路径都遵循拓扑顺序，这意味着不存在向后依赖关系。 当以逆拓扑顺序处理节点时，每个子问题 dp[v] 在用于 dp[u] 之前都已完全解决。 这会创建一个稳定的递归，其中每个 dp 值仅计算一次并且仅取决于已经最终确定的结果。 由于每个有效路径必须沿着图中的边，并且每个扩展在递归过程中都被考虑一次，因此最大计算值对应于真正的最长路径。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import deque

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    indeg = [0] * n

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        indeg[v] += 1

    q = deque([i for i in range(n) if indeg[i] == 0])
    topo = []

    while q:
        u = q.popleft()
        topo.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    dp = [0] * n

    for u in reversed(topo):
        for v in g[u]:
            dp[u] = max(dp[u], 1 + dp[v])

    print(max(dp) if n > 0 else 0)

if __name__ == "__main__":
    solve()
```该实现首先构建邻接表并计算入度以执行标准卡恩算法拓扑排序。 这确保我们避免递归，并且即使对于大型图也保证线性排序。 

一旦建立了拓扑顺序，我们就反向迭代，以便节点的所有后继节点都已被处理。 dp 转换直接镜像从每个节点开始的最长路径的定义。 

一个微妙的点是 dp 被初始化为零，这正确地表示没有传出边的节点贡献的路径长度为零。 另一个重要的细节是，我们将最终答案计算为最大 dp 值，而不是固定节点的 dp，因为路径可以从任何地方开始。

 | 步骤| 节点| dp 之前 | 更新 |

 ## 边缘情况

 对于空边集，例如`n = 3, m = 0`，该算法仍然会产生有效的拓扑顺序，并将 dp 值分配给所有节点，该值为零。 最大值正确地为零，因为不存在转换。 

对于纯链，例如`1 → 2 → 3 → 4`，逆向拓扑处理确保每个 dp 每一步精确地积累一个额外的边，从而产生正确的线性增长。 

对于像这样的分支合并结构`1 → 3, 2 → 3, 3 → 4`，节点 3 被计算一次为 dp[3] = 1，并且两个前任都正确地重用该值而无需重新计算，确认了 DAG 排序的记忆效果。
