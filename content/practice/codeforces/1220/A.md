 ## 解决方案
 ## 问题理解

 我们得到了一组字母，这些字母最初来自于编写几个二进制单词，其中每个单词要么是字符串`"zero"`代表数字 0 或`"one"`代表数字 1。这些单词被连接起来，然后所有字母都被打乱，所以我们失去了除了原始字符计数之外的所有结构。 

我们的任务是重建可能产生这些字母的二进制数，但在所有有效的重建中，我们必须输出最大可能的二进制数。 这意味着我们想要尽可能多的`1`尽可能的数字，因为在二进制表示中任何`1`比一个贡献更多的价值`0`在相同的位置。 

关键的限制是每个字母必须准确使用，并且我们形成的每个数字都必须对应于`"zero"`或者`"one"`。 

输入大小最多为 100000 个字符。 这立即排除了任何试图排列或搜索安排的方法。 在最坏的情况下，即使是二次方法也会太慢。 我们需要纯粹基于计数和贪婪提取的线性或近线性重建。 

当单词之间的字母严重重叠时，就会出现微妙的边缘情况。 例如，`"o"`,`"n"`,`"e"`重叠于`"z"`,`"e"`,`"r"`,`"o"`只在信中`'o'`和`'e'`。 如果不优先考虑提取，那么在没有仔细排序的情况下贪婪地选择单词的天真尝试可能会失败`"one"`第一的。 

另一个边缘情况是当没有完整的单词时`"one"`或者`"zero"`即使字母存在。 例如，`"noe"`不能形成任何一个单词，并且由于约束而不应出现，但中间贪婪逻辑必须避免假设部分匹配有效。 

## 方法

 暴力解释将尝试通过尝试将字母分组为大小为 3 或 4 的块的所有排列并检查每个块是否形成来尝试重建序列`"one"`或者`"zero"`。 即使我们固定分组大小，我们仍然需要尝试字符串分区的组合，字符串随着 n 呈指数增长。 当 n = 100000 时，这是完全不可行的。 

关键的观察是每个数字对应于固定的多组字符。 我们不是任意排列字母，而是将多重集分解为已知的固定多重集：`zero → {z, e, r, o}`

`one → {o, n, e}`这是一个经典的多重集分解问题。 贪心策略是确定每个单词可以独立于字符数形成多少次。 

两个单词之间唯一的耦合是共享的字母`'o'`和`'e'`，但我们可以通过优先提取来干净地解决这个问题`"one"`第一的。 原因是`"one"`用途`'n'`，它没有出现在`"zero"`，因此它是唯一可识别的。 一旦全部`"one"`单词被提取，剩下的字母自然形成`"zero"`如果可能的话。 

数完之后有多少个`"one"`我们可以形成，我们从频率表中减去它们的字母使用情况，然后进行计数`"zero"`。

 ## 算法演练

 我们继续按确定的顺序计算字母并提取单词。 

1. 统计输入字符串中每个字符的出现频率。 这对我们可以形成的单词数量给出了全局限制。 
2. 确定我们可以组成多少次`"one"`。 自从`"one"`需要`'n'`，并且仅`"one"`用途`'n'`，数量`"one"`单词数正好是`'n'`。 
3. 对于每个`"one"`我们删除，我们减少计数`'o'`,`'n'`， 和`'e'`。 此步骤确保我们不会重复使用已提交的信件。 
4.全部删除后`"one"`单词，计算有多少个`"zero"`可以组成单词。 这受到剩余计数的限制`'z'`,`'e'`,`'r'`， 和`'o'`。 由于删除后所有字母都是独立的`"one"`，数量`"zero"`单词受到这些所需字母中最小频率的限制。 
5. 通过打印所有内容构建最终答案`"one"`首先是数字（以最大化二进制值），然后是所有`"zero"`数字。 

排序至关重要，因为通过将 1 放置在较高有效位置来最大化二进制数，并且由于输出是空格分隔的数字，因此将所有 1 放在第一位可确保按字典顺序和数字排列最大输出。 

### 为什么它有效

 正确性依赖于以下事实：`"one"`有一个独特的识别字母`'n'`没有出现在`"zero"`。 这使得数量`"one"`单词是固定的并且独立于任何排序选择。 一旦所有出现`"one"`被删除，剩余的多重集仅包含有效的组合`"zero"`如果保证输入有效的话。 贪婪分离不会失去最优性，因为没有其他方法可以交易`"one"`对于一个`"zero"`不违反固定字母约束。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    cnt = [0] * 26

    for ch in s:
        cnt[ord(ch) - 97] += 1

    o = ord('o') - 97
    n = ord('n') - 97
    e = ord('e') - 97
    z = ord('z') - 97
    r = ord('r') - 97

    ones = cnt[n]

    # build ones
    cnt[o] -= ones
    cnt[n] -= ones
    cnt[e] -= ones

    zeros = min(cnt[z], cnt[e], cnt[r], cnt[o])

    res = []
    res.extend(["1"] * ones)
    res.extend(["0"] * zeros)

    sys.stdout.write(" ".join(res))

if __name__ == "__main__":
    solve()
```该实施完全由频率核算驱动。 我们明确依赖`'n'`作为计数的枢轴`"one"`词，因为它独特地出现在那里。 减去它的贡献后，我们安全地计算`"zero"`从剩余字母开始计数。 

最后的串联步骤确保了排序的正确性，因为所有`"1"`数字放在前面`"0"`数字。 

一个微妙的实现细节是我们必须减去使用的所有字母`"one"`计数前`"zero"`。 如果我们跳过这一步，共享信件如`'o'`和`'e'`将被重复计算，从而产生夸大的数量`"zero"`字。

 ## 边缘情况

 一种边缘情况是当没有`"one"`因为可以形成`'n'`缺席。 用于输入`"zerozero"`，算法集`ones = 0`，并直接计算`"zero"`从剩余的字母中，产生`"0 0"`正确。 

另一种极端情况是字母丰富但不平衡。 为了`"oneoneonezero"`，计数`'n'`严格限制`"one"`的话，确保我们不会过度生产，即使`'o'`和`'e'`很丰富。 

最后，两个单词在字母中完全交错的情况可以安全地处理，因为减去`"one"`字母保证不干扰计数`"zero"`。
