 ## 解决方案
 ## 问题理解

 我们有两个长度相等的大写字符串。 我们可以替换第一个字符串中的字符，并且在所有替换之后，最终的字符串只需要是第二个字符串的字谜词即可。 对于多组字符来说，顺序并不重要，但是在使用最小替换次数的所有有效答案中，我们必须输出按字典顺序最小的结果字符串。 

关键细节是我们并不试图转型`s`进入`t`逐个位置。 我们只关心最终的字符频率与`t`。 

认为`t`包含三个`A`和两个`B`s。 那么最终的字符串也必须恰好包含三个`A`和两个`B`s，无论它们出现在哪里。 

长度可以达到`10^5`，这立即排除了任何二次方。 在没有有效簿记的情况下，我们无法重复重建字符串、多次对大前缀进行排序或贪婪地尝试所有替换选择。 由于字母表仅包含 26 个大写字母，因此频率计数变得非常有吸引力。 一个`O(n * 26)`解决方案完全没问题，同时`O(n^2)`已经在附近了`10^10`最坏情况下的操作。 

字典顺序上最小的要求会产生一些微妙的情况。 

考虑：```
s = BAA
t = AAC
```最少更换次数为`1`。 我们必须更换`B`和`C`, 给予`CAA`。 一个粗心的策略，贪婪地在每个位置放置尽可能小的字母，可能会尝试改变第一个字母`B`进入`A`，但是那样我们就会有太多`A`s，稍后仍需要更换。 

另一个棘手的情况是，当某个字符已经出现过多时，但我们应该延迟替换某些出现的字符。 

例子：```
s = CBA
t = ABB
```我们需要频率`{A:1, B:2}`。 正确答案是：```
ABB
```如果我们贪婪地立即替换第一个超大字符而不检查未来的位置，我们可能会保持领先`C`并修改后面的字母，产生按字典顺序更大的字母。 

当某个字符当前过多时，会发生一种更微妙的情况，但保留较早出现的字符比为后面的位置保存替换字符对字典顺序的帮助要小。 

例子：```
s = BBAA
t = AACC
```我们需要两个替代者。 最好的答案是：```
AACC
```天真的“仅在强制时替换”实现可能会意外保留第一个`B`，后来发现必须引入一个额外的`A`无论如何，产生一个按字典顺序更大的答案。 

核心困难是同时平衡两个目标：

 首先，使用尽可能少的替换次数。 

其次，在所有此类解决方案中，使最早的位置尽可能小。 

## 方法

 思考这个问题的蛮力方法是生成以下的所有字谜`t`，然后检查有多少个位置与`s`。 不同位置的数量等于所需替换的数量。 在所有具有最小距离的字谜中，我们选择字典顺序最小的一个。 

这是正确的，因为每个有效的最终字符串都必须是以下的字谜词`t`。 问题是`t`最多可以有`10^5`人物。 即使是长度`20`，不同排列的数量已经是巨大的。 全面列举是没有希望的。 

更实用的蛮力变体会贪婪地尝试每个位置的所有可能的替换，同时保持频率有效性。 对于每个索引，我们可以测试所有26个字母，看看剩下的后缀是否仍然能够满足目标频率。 如果简单地实现的话，这仍然会变得昂贵，特别是在重复频率重新计算的情况下。 

重要的观察是，最小替换数量完全由频率重叠决定。 

如果`s`已经包含五个`A`沙`t`需要三个`A`s，那么至少有两个`A`s 必须消失。 如果`s`包含一个`C`和`t`需要四个`C`s，那么我们必须创建三个新的`C`在某处。 

那么问题就变成了：

 我们确切地知道哪些字母过多，哪些字母缺失。 我们如何重新分配它们以获得字典顺序最小的字符串？ 

这导致了贪婪的从左到右的策略。 

在每个位置：

 如果仍然需要当前角色，我们可能想保留它。 

但是，如果用较小的缺失字符替换它可以改善字典顺序，我们应该立即这样做。 

如果当前字符过多并且存在较小的缺失字符，那么现在更改总是有益的，因为较早的位置主导字典顺序。 

如果仅保留较大的缺失字符，我们更愿意尽可能延迟替换，因为保留较小的当前字符有助于保持前缀最小。 

小字母表使簿记变得容易。 我们维护每个字母仍需要多少个副本，以及字符串中稍后还保留多少个副本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳 | O(n * 26) | O(26) | 已接受 |

 ## 算法演练

 1. 统计每个字符出现的频率`t`。 

这些计数准确地描述了最终字符串必须包含的内容。 
2. 统计每个字符出现的频率`s`。 

比较两个频率数组可以告诉我们哪些字母过多，哪些字母缺失。 
3. 从左到右遍历字符串。 

我们贪婪地决定每个位置的最终值，因为字典顺序首先取决于较早的位置。 
4.对于当前角色`c`，首先减少其在后缀中的剩余计数。 

这告诉我们有多少个副本`c`如果我们选择不修改此事件，以后仍然存在。 
5. 检查是否`c`是过度的。 

如果当前总计数为`c`已经不大于要求了，我们必须保留这个字符。 更换它只会造成不必要的额外操作。 
6.如果`c`过多，寻找最小的缺失字符`x`。 

我们尝试来信`'A'`向上，因为我们想要字典顺序最小的结果。 
7. 如果`x < c`，立即更换。 

较早位置的较小字母总是可以改善答案。 
8.如果`x > c`，仅当我们无法安全保存时才更换`c`。 

具体来说，如果剩余的未来副本`c`少于所需的数量，则这种情况必须保留。 否则我们可以推迟更换。 
9. 每当发生替换时，更新两个频率数组。 

过多的字母会丢失一次，而丢失的字母会增加一次。 
10. 继续，直到处理完所有位置。 

### 为什么它有效

 该算法保持一个简单的不变量：

 在处理每个位置之前，当前频率数组表示部分修改的字符串中仍然存在的字符。 

每当我们替换一个字符时，我们总是将一个单位从多余的字母移动到缺失的字母，因此保留了最小替换计数。 

字典序最优性来自于从左到右的贪婪选择。 如果可以将较小的缺失字母放置在当前位置，那么延迟改进永远不会有帮助，因为词典比较取决于最早的不同位置。 相反，当仅存在较大的替换字母时，我们会尽可能保留当前较小的字符，并将不可避免的增加推迟到稍后的位置。 

因为每个决策都是局部最优的，并且永远不会损害未来的可行性，所以最终的字符串是所有最小替换解决方案中按字典顺序最小的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = list(input().strip())
    t = input().strip()

    need = [0] * 26
    cur = [0] * 26

    for ch in t:
        need[ord(ch) - 65] += 1

    for ch in s:
        cur[ord(ch) - 65] += 1

    changes = 0

    for i in range(len(s)):
        c = ord(s[i]) - 65

        # this character is not excessive
        if cur[c] <= need[c]:
            continue

        for x in range(26):
            if cur[x] < need[x]:
                # smaller character, always beneficial
                if x < c:
                    cur[c] -= 1
                    cur[x] += 1
                    s[i] = chr(x + 65)
                    changes += 1
                    break

                # larger character
                # replace only if enough copies remain later
                elif x > c:
                    if cur[c] - 1 >= need[c]:
                        cur[c] -= 1
                        cur[x] += 1
                        s[i] = chr(x + 65)
                        changes += 1
                    break

    print(changes)
    print("".join(s))

solve()
```两个频率阵列是解决方案的整个支柱。`need`存储每个字符在最终字符串中必须出现的份数。`cur`存储我们不断发展的答案中当前存在多少个副本。 

遍历是贪婪且永久的。 一旦我们越过了某个位置，我们就不会再重新审视它。 这是安全的，因为字典顺序将较早的位置完全优先于较晚的位置。 

条件：```
if cur[c] <= need[c]:
```非常重要。 说明这个角色已经不再多余了。 替换它会迫使我们在其他地方重新创建相同的角色，从而不必要地增加操作次数。 

第二个微妙的部分是：```
if cur[c] - 1 >= need[c]:
```这将检查我们是否可以安全地丢弃当前出现的字符，并且稍后仍然拥有该字符的足够副本。 缺少这个条件会导致许多错误的答案，因为我们可能会过早删除一封信的太多副本。 

由于字母大小是恒定的，因此对所有 26 个字母进行循环的成本很低。 即使与`10^5`角色，总工作量保持不变`2.6 * 10^6`运营。

def solve():

                        cur[x] += 1

    out = io.StringIO()
    backup = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup
    return out.getvalue()

 ## 边缘情况

 考虑：```
s = BAA
t = AAC
```目标需要一个`C`，但替换第一个`B`立即给出：```
CAA
```该算法处理第一个位置：`B`过多，最小的缺失字母是`C`。 

自从`C > B`，算法检查是否足够`B`稍后再留。 他们不这样做，因为这是唯一`B`。 所以强制更换。 

最终答案变成：```
CAA
```这是最佳的。 

现在考虑：```
s = ABA
t = CBA
```一开始`A`，最小的缺失字母是`C`。 

自从`C > A`，立即替换会使前缀变得更糟。 该算法保留了这个`A`因为另一个`A`稍后存在并且可以替换。 

在最终位置，需要更换：```
ABC
```这证明了核心的贪婪原则：尽可能推迟有害的替代品。 

最后，考虑一种早期改进总是正确的情况：```
s = CBA
t = ABB
```目标频率需要额外`B`并删除`C`。 

在位置`0`,`C`过多，最小的缺失字母是`B`。 

因为`B < C`，立即替换严格提高字典顺序。 该算法立即执行替换并生成：```
BBA
```任何以以下开头的解决方案`C`按字典顺序会更大。
