 ## 解决方案
 ## 问题理解

 我们在坐标平面上放置了一组高尔夫球洞。 球员在 Meeseeks 建议的点开始发球。 唯一允许的移动包括两次击球：首先球只能向左移动，然后只能向下移动。 两个镜头的长度可以是任何非负值。 

对于起始位置`(a, b)`，这两次射击后的最终位置可以是任意坐标满足的孔`x <= a`和`y <= b`。 发射的顺序不会改变此条件，因为第一次发射仅减小 x 坐标，第二次发射仅减小 y 坐标。 

输入最多可达`100000`孔和最多`100000`建议。 对于每一个建议，我们都必须回答是否至少有一个洞是可以到达的。 

边界立即排除了针对每个洞检查每个建议的可能性。 直接解决方案最多需要`10^10`坐标比较，这远远超出了典型的两秒限制所允许的范围。 我们需要对这些漏洞进行预处理，以便可以在对数时间内回答每个查询。 

主要的边缘情况来自运动方向。 即使其他坐标合适，也无法到达具有较大 x 坐标或较大 y 坐标的孔。 例如：```
Input
2
5 5
10 1
3
6 6
9 2
4 10
```第一个查询应该输出`YES`因为`(5,5)`位于以下左侧`(6,6)`。 第二个查询应该输出`NO`因为`(5,5)`x 坐标较小，但另一个孔`(10,1)`太右了。 仅检查一个坐标的粗心解决方案会错误地接受它。 

另一个常见的错误是忘记起点本身也可以是有效的目的地。 例如：```
Input
1
7 4
1
7 4
```答案是`YES`，因为两个镜头长度都可以为零。 在这种情况下，需要严格较小坐标的解决方案会失败。 

重复的孔也是可能的。 例如：```
Input
3
2 3
2 3
5 1
1
2 3
```答案是`YES`。 重复项不会改变逻辑，但在预处理时错误地删除点的实现可能会意外丢失有效信息。 

## 方法

 蛮力方法很简单。 对于每一个建议`(a, b)`，扫描所有孔洞，检查是否存在孔洞`(x, y)`和`x <= a`和`y <= b`。 这是正确的，因为它准确地测试了可达性条件。 然而，随着`n`孔和`q`查询，最坏情况执行`n * q`比较。 两个值都等于`100000`，这变成了`10^10`操作，速度太慢。 

条件的结构为我们提供了更快的方法。 每个查询都会询问左下角矩形中是否存在一个点`(a, b)`。 我们可以将孔预处理成一种形式，其中答案只是比较，而不是每次都搜索这个矩形。 

按 x 坐标对所有孔进行排序。 从左向右移动时，保持迄今为止看到的所有孔中最大的 y 坐标。 对于任何可能的 x 边界，该值告诉我们仍然可以水平到达的最高孔。 查询`(a, b)`只需要知道孔之间是否有`x <= a`至少有一个具有最大 y`b`。 

这将问题转换为前缀最大查询。 对孔进行排序后，我们存储 x 坐标数组和相应的最大 y 值。 每个查询都使用二分搜索来查找最后一个孔`x <= a`，然后检查存储的最大 y。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(1) | O(1) | 太慢了 |
 | 最佳 | O((n + q) log n) | O((n + q) log n) | O(n) | 已接受 |

 ## 算法演练

 1. 按 x 坐标对所有孔进行排序。 如果两个孔具有相同的 x 坐标，它们的相对顺序并不重要，因为它们都将成为同一前缀的一部分。 
2.构建前缀最大数组。 对于已排序孔中的每个位置，存储从开始到该位置的所有孔中最大的 y 坐标。 该值表示所有 x 坐标不大于当前 x 坐标的孔中可到达的最高孔。 
3. 对于每一条 Meeseeks 的建议`(a, b)`，对已排序的 x 坐标使用二分搜索来查找包含孔的最后一个索引`x <= a`。 该索引之后的所有孔都无法到达，因为它们的 x 坐标太大。 
4. 如果不存在这样的索引，则起点左边没有洞，所以答案是`NO`。 否则，将该索引处的前缀最大 y 坐标与`b`。 如果至少是`b`，存在一些可到达的洞，答案是`YES`。 

为什么有效：按x排序后，每个前缀都恰好包含满足水平要求的孔。 该前缀中存储的最大 y 表示这些孔中可能的最佳垂直位置。 如果甚至最高的 y 都低于查询的 y 坐标，则前缀中的每个孔都太低。 如果最大值达到查询的 y 坐标，则该孔满足两个坐标并且可以到达。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    holes = []

    for _ in range(n):
        x, y = map(int, input().split())
        holes.append((x, y))

    holes.sort()

    xs = []
    pref_y = []

    best = 0
    for x, y in holes:
        xs.append(x)
        best = max(best, y)
        pref_y.append(best)

    q = int(input())
    ans = []

    import bisect

    for _ in range(q):
        a, b = map(int, input().split())

        idx = bisect.bisect_right(xs, a) - 1

        if idx >= 0 and pref_y[idx] >= b:
            ans.append("YES")
        else:
            ans.append("NO")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```排序步骤为前缀处理准备点。 排序后，每个以索引结尾的前缀`i`最多恰好包含 x 坐标的孔`xs[i]`。 

这`pref_y`数组存储每个前缀可用的最强垂直选项。 仅保留最大 y 就足够了，因为查询不关心哪个孔提供它，只关心某个孔是否达到足够高。 

对于每个查询，`bisect_right`找到第一个位置`a`可以在保持 x 数组排序的同时插入。 减一给出最后一个有效孔`x <= a`。 与的比较`pref_y[idx]`处理垂直要求。 

二分查找边界是最容易出错的地方。 使用`bisect_right`而不是`bisect_left`是必要的，因为可以到达正好位于起始 x 坐标上的孔。

 | 测量 | 复杂性 | 说明|

 | 时间 | O((n + q) log n) | O((n + q) log n) | 排序成本为 O(n log n)，每个查询都使用一次二分查找。 |

 该解决方案仅对每个查询执行对数量的工作，因此`100000`孔和`100000`查询很容易符合限制。

 ## 边缘情况

 对于第一个边缘情况：```
2
5 5
10 1
1
9 2
```该算法对洞进行排序，发现只有`(5,5)`属于前缀为`x <= 9`。 该前缀中的最大 y 是`5`，这至少是`2`，所以答案是`YES`。 

对于与查询相同的数据`(9,6)`，前缀最大值仍然是`5`，但现在它低于所需的 y 坐标。 算法返回`NO`，正确拒绝水平方向可到达但垂直方向太高的点。 

对于零距离移动情况：```
1
7 4
1
7 4
```二分查找找到漏洞是因为`x <= a`当值相等时为真。 前缀最大 y 也等于`b`，所以答案是`YES`。 

对于重复孔：```
3
2 3
2 3
5 1
1
2 3
```两份副本`(2,3)`排序后出现在开头。 前缀最大值变为`3`，查询成功。 该算法不依赖于唯一性，因此重复项不需要特殊处理。
