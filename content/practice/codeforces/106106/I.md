 ## 问题理解

 该任务要求进行简单的数学观察。 我们得到一个数字`k`并且需要找到最大的正整数`n`这样`n`不大于`k`和价值`n`正好等于它的阶乘。 数字的阶乘是直到该数字的所有正整数的乘积。 原始问题来自 Codeforces Gym 106106，问题 I，“Немножко математики”。 

输入仅包含一个整数`k`， 和`1 ≤ k ≤ 10^5`。 由于上限很小，因此已经可以进行直接模拟，但更有用的观察是阶乘增长得非常快。 在前几个值之后，`n!`变得比`n`，因此不能有太多候选者需要检查。 

唯一满足的正整数`n = n!`是`1`和`2`。 为了`n = 1`，阶乘是`1! = 1`。 为了`n = 2`，阶乘是`2! = 2`。 对于每一个`n ≥ 3`，阶乘至少包含乘法`2`，结果严格大于`n`。 

主要的边缘情况是`k`正是这些有效值之一或位于它们之间时。 

对于输入：```
1
```正确的输出是：```
1
```一个粗心的解决方案，只检查是否`k`如果它假设总是有一个较小的答案，那么它本身满足条件可能会失败。 

对于输入：```
3
```正确的输出是：```
2
```价值`3`无效，因为`3! = 6`，因此答案必须下移到前一个有效数字。 

对于输入：```
100000
```正确的输出是：```
2
```在具有固定大小整数的语言中，如果暴力阶乘计算继续进行不必要的乘法，则可能会溢出，即使答案已经已知。 

## 方法

 最简单的方法是迭代每个数字`1`到`k`，计算其阶乘，并记住阶乘等于其自身的最大数。 这是正确的，因为它直接检查有效答案的定义。 然而，尽管`k`只是`100000`，无需重复计算阶乘。 阶乘值很快就会变得巨大，存储或计算这些值会增加复杂性，而不会提供有用的信息。 

关键的观察结果是方程`n = n!`是极其严格的。 一次`n`达到`3`，阶乘立即变大：```
3! = 6 > 3
```对于每一个更大的数字，差距只会增加。 这留下了两个可能的答案：`1`和`2`。 

那么问题就变成了一个简单的比较。 如果`k`至少是`2`，可用的最大有效值为`2`。 否则，唯一可能的答案是`1`。

 ## 算法演练

 1.读取数值`k`。 
2. 检查是否`k`至少是`2`。 价值`2`是有效的，因为`2! = 2`，并且没有更大的正整数可以满足该方程。 
3.如果`k`小于`2`， 输出`1`， 因为`1! = 1`是唯一剩余的有效值。 

为什么它有效：阶乘函数仅在以下位置有一个固定点`1`和`2`正整数之间。 一旦数量达到`3`，乘以所有先前的正整数会使阶乘永远大于原始数字。 

## 为什么它有效

 该算法依赖于这样一个事实：只有两个正整数的数字及其阶乘相等。 价值观`1`和`2`可以直接验证。 对于每一个`n ≥ 3`，我们有：```
n! = 1 * 2 * 3 * ... * n
```产品包含以下因素`1 * 2 * ... * (n - 1)`，这至少已经是`2`对于这些值，并乘以`n`使阶乘严格大于`n`。 因此没有值大于`2`可以是一个答案。 该算法仅在两个可能的有效数字之间进行选择，因此它总是返回不超过的最大数字`k`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input())
    if k >= 2:
        print(2)
    else:
        print(1)

if __name__ == "__main__":
    solve()
```实现直接遵循数学观察。 条件`k >= 2`涵盖了所有可以找到答案的情况`2`。 否则，`k`必须是`1`，答案也是`1`。 

代码中没有阶乘计算。 这避免了不必要的乘法，并消除了具有较小整数类型的语言中整数溢出的任何风险。

 ## 边缘情况

 对于`k = 1`，算法检查`k >= 2`，这是错误的，并且返回`1`。 这是正确的，因为`1! = 1`，并且没有更小的正整数候选。 

为了`k = 3`，算法返回`2`立即地。 虽然`3`足够大，可以考虑，但不能使用，因为`3! = 6`。 与的比较`2`捕获低于其的最大有效值。 

为了`k = 100000`，该算法不会尝试计算任何阶乘。 它返回`2`在一次比较后，避免阶乘值不必要的增长，同时仍然产生正确的结果。
