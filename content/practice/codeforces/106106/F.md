 ## 解决方案
 ## 问题理解

 我们有一个栅栏，由`n`垂直的板彼此相邻放置。 木板`i`有高度`h[i]`，所以如果它接收到一种颜色，它就会准确消耗`h[i]`平方厘米的油漆。 每块木板必须漆成红色或绿色。 

红色油漆最多可以覆盖`a`平方厘米，绿色油漆最多可以覆盖`b`平方厘米。 在所有有效的着色中，我们需要一种不同颜色的相邻板具有尽可能最小的总接触长度的着色。 对于两个相邻的板，接触长度是其两个高度中较短的一个，因为板仅在重叠的垂直段上接触。 

例如，如果两个相邻的板具有高度`5`和`3`和不同的颜色，他们贡献`3`到不吸引力值。 If their colors are equal, they contribute nothing.

 The input size gives the direction of the solution. 板数仅`200`，但涂料容量可达`40000`。 涉及板数和使用的红色区域的状态空间是现实的，同时尝试所有`2^n`着色是不可能的。 即使与`n = 40`，蛮力已经超出了实际限制，并且`n = 200`使其完全不可行。 

疑难案件不仅投入大。 解决方案还必须处理以下情况：未使用一种颜色、油漆限制恰好等于所需区域，以及局部廉价的颜色选择会在以后产生昂贵的更改。 

考虑这个输入：```
1
0 5
5
```唯一一块板有高度`5`。 正确的输出是：```
0
```粗心的解决方案可能会认为需要两种颜色并拒绝它，但允许一种颜色保持不使用。 

另一个重要案例是：```
3
3 3
2 2 2
```正确的输出是：```
-1
```围栏总面积为`6`，因此两种颜色加在一起就有足够的容量。 然而，两种颜色都不能占据全部三块板，因为每种颜色都有容量`3`，而每个董事会都做出贡献`2`。 州政府必须跟踪准确的可实现的涂漆面积，而不仅仅是总的可用容量。 

第三种情况是：```
4
10 10
8 1 8 1
```简单地将最高的板组合在一起并不能找到最佳的着色。 过渡成本取决于相邻的高度，因此最佳决策取决于前一块板的颜色。 

## 方法

 直接的方法是尝试栅栏的所有可能的颜色。 对于每种颜色，我们计算总红色面积、绿色面积以及不同颜色之间每个边界的成本。 此方法是正确的，因为每个可能的分配都会被检查，但它会检查`2^n`的可能性。 和`n = 200`，这远远超出了任何可行的操作次数。 

对我们有帮助的结构是相邻板之间的唯一交互是前一块板的颜色。 当我们决定下一块板的颜色时，我们需要添加的唯一新成本是该颜色是否与前一个不同。 早期董事会的完整历史是不必要的。 

这表明动态规划。 我们从左到右处理木板，并在为前缀着色后存储最小的不美观性。 国家需要记住所使用的红色油漆的量和最后涂漆板的颜色。 绿色量不需要存储，因为处理后的前缀总高度是已知的，因此可以计算绿色使用量。 

蛮力之所以有效，是因为它探索了所有可能的先前颜色历史，但一旦它们具有相同的红色用法和结束颜色，大多数历史都是等效的。 动态规划将这些等价情况合并为一种状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 太慢了 |
 | 最佳 | O(n * a * 2) | O(a * 2) | 已接受 |

 ## 算法演练

 1. 从左到右处理板材。 为每种可能的红色涂料使用维护两个动态编程值。 一个值代表当前最后一块板为红色时的最小不吸引力，另一个值代表当前最后一块板为绿色时的相同情况。 

该状态是足够的，因为未来的决策只关心之前的板颜色以及已经消耗了多少红色容量。 
2. 单独初始化第一块板。 如果第一块板是红色的，则红色的用法是`h[0]`成本是`0`。 如果是绿色，则红色的用法是`0`成本是`0`。 

第一块板没有以前的边框，因此不会增加任何吸引力。 
3. 对于每个下一个板，创建一个新的动态编程数组。 尝试将板子涂成红色，并尝试将每个可到达的先前状态涂成绿色。 

如果颜色保持不变，则成本不会改变。 如果颜色发生变化，添加`min(h[i-1], h[i])`，这是新创建的坏边框的长度。 
4. 将板涂成红色时，将跟踪的红色用量增加其高度。 涂成绿色时，保持红色用量不变。 

由于围栏的总高度是固定的，果岭容量检查被推迟到最后。 对于使用红色的最终状态`r`，绿色用量为`total_height - r`。 
5、所有板子加工完成后，检查各个状态。 如果红色使用量最多为，则状态有效`a`且绿色用量最多为`b`。 这些州中成本最小的就是答案。 如果没有状态有效，则输出`-1`。 

为什么它有效：

 动态规划的不变性是在处理完第一个`i`板，每个存储的状态都包含其精确的红色使用和最终板颜色的最小可能的不吸引力。 添加下一块板时，会考虑每种可能的颜色选择，并且对成本的唯一新贡献是与前一块板的边界。 由于状态准确地保留了未来选择所需的信息，因此不会丢弃任何最佳解决方案。 在最终板之后，所有有效的完整着色都由某种状态表示，因此取最小值给出最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a, b = map(int, input().split())
    h = list(map(int, input().split()))

    INF = 10**18

    dp_red = [INF] * (a + 1)
    dp_green = [INF] * (a + 1)

    if h[0] <= a:
        dp_red[h[0]] = 0
    dp_green[0] = 0

    total = h[0]

    for i in range(1, n):
        nh = h[i]
        total += nh
        ndp_red = [INF] * (a + 1)
        ndp_green = [INF] * (a + 1)

        border = min(h[i - 1], h[i])

        for red_used in range(a + 1):
            if dp_red[red_used] != INF:
                if red_used + nh <= a:
                    ndp_red[red_used + nh] = min(
                        ndp_red[red_used + nh],
                        dp_red[red_used]
                    )
                ndp_green[red_used] = min(
                    ndp_green[red_used],
                    dp_red[red_used] + border
                )

            if dp_green[red_used] != INF:
                if red_used + nh <= a:
                    ndp_red[red_used + nh] = min(
                        ndp_red[red_used + nh],
                        dp_green[red_used] + border
                    )
                ndp_green[red_used] = min(
                    ndp_green[red_used],
                    dp_green[red_used]
                )

        dp_red, dp_green = ndp_red, ndp_green

    ans = INF
    for red_used in range(a + 1):
        green_used = total - red_used
        if green_used <= b:
            ans = min(ans, dp_red[red_used], dp_green[red_used])

    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```数组`dp_red`和`dp_green`仅存储可达到的红色油漆量。 它们的指数是迄今为止使用的红色区域，这是唯一需要的容量维度。 

初始化单独处理第一块板，因为没有前一块板可供比较。 以后的每次转换都会考虑两种可能的新颜色，并仅在颜色发生变化时才添加边框成本。 

绿色量永远不会被存储。 最后，围栏总面积减去存储的红色面积即为绿色面积。 这可以避免通过跟踪两种颜色而使状态大小加倍。 

支票`red_used + nh <= a`防止创建无效的红色状态。 自从`a`至多是`40000`，整数值对于 Python 整数来说仍然足够小，无需任何特殊处理。

 ## 边缘情况

 对于单板情况：```
1
0 5
5
```初始状态使板进入绿色状态并使用红色`0`。 最终检查发现绿色使用情况是`5`，符合极限，并返回`0`因为不存在相邻对。 

对于不可能分布的情况：```
3
3 3
2 2 2
```动态规划创建具有红色使用的状态`0`,`2`,`4`，等等，只有当它们实际上可以到达时。 最终过滤器删除每个状态，因为有效状态最多需要红色使用和绿色使用`3`，这是不可能发生的。 答案仍然是无穷大并转换为`-1`。 

对于不使用一种颜色的情况：```
5
0 15
3 3 3 3 3
```每个红色转换都会被拒绝，因为红色容量为零。 唯一幸存的状态是绿色状态，并且由于所有相邻的板都共享相同的颜色，因此缺乏吸引力`0`。
