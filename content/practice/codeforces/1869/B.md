 ## 解决方案
 ## 问题理解

 我们收到了几个测试用例，每个测试用例都描述了飞机上的完整加权旅行系统。 每个城市都是一个具有整数坐标的点，我们可以在任意一对城市之间直接飞行。 航班费用取决于两个端点是否属于前 k 个城市。 如果两个城市都是主要城市，则航班免费。 否则，成本就是它们之间的曼哈顿距离。 

任务是找到从出发城市 a 到目的地城市 b 的最低总成本，我们可以在目的地城市 b 乘坐任何序列的航班和中途停留。 由于航班形成一个完整的图，在主要城市之间具有特殊的零成本边缘，因此问题本质上是在具有非常结构化的成本规则的密集加权图中找到最短路径。 

这些约束使得每个测试边界线具有 O(n^2) 条边的朴素最短路径方法，但如果仔细处理，总和 n ≤ 2·10^5 是可以接受的。 然而，使用显式完整图运行 Dijkstra 是不可能的，因为它需要考虑每个测试用例的 O(n^2) 条边。 

当 k 很大时，会出现一个微妙的困难。 如果许多城市都是大城市，它们就会形成一个零成本的集团，这意味着我们可以在它们之间自由流动。 这创建了一个“隐形传输骨干网”，可以大大降低成本，但前提是我们以最佳方式使用它。 

打破天真的思维的极端情况包括：

 总是使用最近城市的贪婪选择会失败，因为隐形传送可以绕过很远的距离。 

例如，如果两个主要城市相距较远，但距离不同地区较近，则在内部经过它们的旅行是免费的，但到达它们则不然。 忽视使用大城市作为中间枢纽的幼稚策略将会高估成本。 

另一种失败情况是当 k = 0 时，这意味着没有自由边。 然后问题简化为完整曼哈顿图中的纯最短路径，其中最优路径始终是从 a 到 b 的直接路径。 

## 方法

 暴力解决方案会将问题视为完整的加权图，并使用所有 O(n^2) 边运行 Dijkstra 算法。 对于每对城市，我们计算曼哈顿距离，除非两个城市都是主要城市，在这种情况下，边权重为零。 这是正确的，因为每个可能的航班都被明确考虑。 

然而，这需要评估每个测试用例的 O(n^2) 次转换，当 n 很大时这是不可能的。 当总 n 高达 2·10^5 时，即使单个密集图传递也会超出时间限制。 

关键的观察结果是，零成本边缘的结构将所有主要城市折叠成内部成本为零的单个连接组件。 一旦进入主要城市集，您就可以在其中自由移动并从任何主要城市退出。 这意味着我们不考虑所有专业到专业的转变，而只关心是否可以利用这个“自由枢纽”来减少两点之间的距离。 

因此最短路径减少为少量候选策略。 我们要么使用曼哈顿距离直接从a到b，要么使用主要城市群作为传送桥：从a到某个主要城市，在主要城市之间自由移动，然后从另一个主要城市到b。 由于专业之间的内部流动是自由的，这相当于最小化：

 distance(a, u) + distance(v, b)，其中 u 和 v 是任何主要城市。 

这将问题减少到检查一小组候选点而不是所有对。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（完整图上的 Dijkstra）| O(n²) | O(n²) | 太慢了 |
 | 最优（使用主要城市减少）| 每次测试 O(n) | O(n) | 已接受 |

 ## 算法演练

1. 计算城市 a 和城市 b 之间的曼哈顿直接距离。 这始终是一个有效的答案，因为我们可以在任意两个城市之间直飞。 
2. 如果没有主要城市（k = 0），则立即返回这个直达距离。 如果没有自由边，任何中间结构都无法改善路径。 
3. 如果至少有一个主要城市，请计算使用主要城市群作为桥梁的最佳方式。 为此，我们考虑将 a 连接到任何主要城市，将 b 连接到任何主要城市的成本有多低。 
4. 计算从城市a 到任意主要城市的最短距离。 这是进入免费传送网络最便宜的方式。 
5. 计算从任意主要城市到城市 b 的最短距离。 这是退出免费网络的最便宜的方式。 
6. 将这两个值相加，形成使用主要城市路线的候选答案。 
7. 最终答案是直接路径和主要城市桥梁路径之间的最小值。 

我们只需要到主要集合的最小距离的原因是，在该集合内的移动成本为零，因此我们永远不需要跟踪我们进入或退出哪个特定的主要城市，超出了最佳可能的进入和退出成本。 

为什么有效：任何最佳路径都可以分解为三段，从a到某个主要城市、在主要组成部分内以及从a主要城市到b。 中间部分的成本为零，因此不影响最优性。 由于所有主要城市都可以零成本相互到达，因此只有最佳的入口和出口点才重要，从而将整个子图折叠成单个零权重节点。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def dist(i, j, xs, ys):
    return abs(xs[i] - xs[j]) + abs(ys[i] - ys[j])

def solve():
    n, k, a, b = map(int, input().split())
    a -= 1
    b -= 1

    x = [0] * n
    y = [0] * n

    for i in range(n):
        x[i], y[i] = map(int, input().split())

    direct = abs(x[a] - x[b]) + abs(y[a] - y[b])

    if k == 0:
        print(direct)
        return

    majors = list(range(k))

    min_a_to_major = float('inf')
    min_b_to_major = float('inf')

    for i in majors:
        min_a_to_major = min(min_a_to_major,
                             abs(x[a] - x[i]) + abs(y[a] - y[i]))
        min_b_to_major = min(min_b_to_major,
                             abs(x[b] - x[i]) + abs(y[b] - y[i]))

    via_major = min_a_to_major + min_b_to_major

    print(min(direct, via_major))

t = int(input())
for _ in range(t):
    solve()
```该实现直接计算相关点之间的曼哈顿距离。 关键的简化是在评估进入和退出成本时仅关注 k 个主要城市。 这避免了构建任何图形结构。 

索引时必须小心，因为输入使用从 1 开始的城市标签，但数组是从 0 开始的。 另一个微妙的点是单独处理 k = 0 以避免对空主要集进行不必要的迭代。

 ## 边缘情况

 当k = 0时，算法永远不会进入主要城市循环，直接返回a和b之间的曼哈顿距离。 这与不存在零成本边缘的事实相匹配，因此每条路径都会折叠成单个直飞航班。 

当 k = n 时，每个城市都是主要城市，因此所有旅行成本都为零。 该算法正确地计算了最小距离，但仍然返回零，因为在所有情况下进入和退出专业的成本都为零。 

当a或b本身是大城市时，进入或退出成本自动为零。 主要城市的计算最小值自然包括该城市本身，确保算法不会错过我们在零成本组件内开始或结束的最佳路径。
