 ## 问题理解

 我们有一个聚会`n`人，每人带来一定数量的糖果。 每个人最多可以向另一个人赠送二次方数量的糖果，并且每个人最多可以向一个人赠送并从最多一个人那里收到糖果。 目标是确定是否可以重新排列糖果，以便每个人最终得到相同数量的糖果。 

输入提供多个测试用例。 对于每个测试用例，我们得到人数`n`和一个数组`a`初始糖果数量。 输出是`"Yes"`如果可以重新分配糖果以使所有计数在给定规则下相等，否则`"No"`。 

限制因素需要仔细考虑。`n`可以达到`2*10^5`，和总计`n`所有测试用例不超过`2*10^5`。 每个糖果数量最多可达`10^9`。 这排除了尝试直接模拟所有可能的传输或尝试给予和接收的所有子集的算法 - 暴力将需要指数级的许多操作。 相反，我们需要一种利用二次幂特性和糖果数量之间差异的方法。 

当每个人都拥有相同数量的糖果时，就会出现不明显的边缘情况。 答案应该是`"Yes"`即使不需要任何动作。 另一个微妙的情况是，差异不是二的幂，或者捐赠者和接收者之间无法一对一匹配。 例如，如果一个人有 1 颗糖果，另一个人有 3 颗糖果，则不可能通过一次 2 的幂步转移来平衡它们，因为这里 2 不是 2 的幂差。 

## 方法

 暴力方法将尝试枚举每个人所有可能的转移，并检查是否存在有效的重新分配。 为了`n = 10^5`，这种方法会立即失败，因为候选移动的数量呈指数增长，并且检查所有组合是不可行的。 

关键的见解是，每次转移都是 2 的幂，每个人最多可以参与一次给予和一次接受行动。 这一限制使我们能够推理差异而不是模拟传输。 让`target`是糖果的平均数量。 任何人拥有超过`target`必须准确地给出差额，而拥有较少的人必须准确地收到差额。 如果所有差异都可以表示为 2 的不同幂的总和并且可以唯一配对（每个捐赠者与接收者），那么重新分配是可能的。 

贪心方法如下：计算每人的目标糖果，计算差异，并检查每个盈余和赤字是否可以通过唯一的二次幂转移来解决。 这将问题简化为计数位 - 每个位位置的盈余和赤字必须精确平衡。

 ## 算法演练

 1. 对于每个测试用例，请阅读`n`和数组`a`糖果数。 计算糖果的总和，`total`。 
2. 检查是否`total`可以整除`n`。 如果不是，均等分配是不可能的，输出`"No"`。 
3. 计算`target = total // n`。 
4. 初始化两个列表：`give`每个人必须奉献的金额（正差）和`receive`每个人必须收到的金额（绝对值的负差）。 
5. 对于每个人，计算`diff = a[i] - target`。 如果`diff > 0`，附加到`give`; 如果`diff < 0`，将绝对值附加到`receive`。 
6. 对于中的每个值`give`和`receive`，使用位运算将其分解为两个不同幂的和。 跟踪每个二的幂需要多少次传输。 
7. 比较每个 2 的幂所需的传输次数`give`和`receive`。 如果完全匹配，则输出`"Yes"`。 否则，输出`"No"`。 

其原理：每个人最多向一个人捐赠，最多从一个人接收，因此唯一允许的移动方式就是每个 2 的幂数中，一名捐赠者对应一名接收者。 平衡二的幂计数可确保所有所需传输都存在一对一映射。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can_equalize(a):
    n = len(a)
    total = sum(a)
    if total % n != 0:
        return False
    target = total // n
    give_bits = [0] * 31
    receive_bits = [0] * 31
    for x in a:
        diff = x - target
        if diff > 0:
            for i in range(31):
                if diff & (1 << i):
                    give_bits[i] += 1
        elif diff < 0:
            diff = -diff
            for i in range(31):
                if diff & (1 << i):
                    receive_bits[i] += 1
    return give_bits == receive_bits

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print("Yes" if can_equalize(a) else "No")
```该解决方案将每个差异分解为 2 的幂，并计算每个位需要多少个。 使用大小为 31 的列表就足够了，因为`a_i <= 10^9`（适合 30 位）。 比较这些计数可以保证每笔盈余都可以通过独特的一对一的二次幂转移来匹配赤字。 

## 工作示例

 **示例1：**`a = [2, 4, 3]`目标=`(2+4+3)/3 = 3`差异：`[-1, +1, 0]`- 给出：1（从 4 到 2）→ 位 0 = 1
 - 接收：1（从 2 到 4）→ 位 0 = 1

 计数匹配 → 是

 **示例2：**`a = [1, 4, 7, 1, 5, 4]`目标=`(1+4+7+1+5+4)/6 = 22/6 ≈ 3.666`→ 非整数 → 否

 这表明，当总数不能被整除时，该算法可以正确检测不可能的情况`n`。
