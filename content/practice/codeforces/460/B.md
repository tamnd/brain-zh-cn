 ## 解决方案
 ## 问题理解

 任务要求我们找到满足方程的所有小于十亿的正整数$$x = b \cdot s(x) \cdot a + c$$在哪里$a$,$b$， 和$c$给定常数，并且$s(x)$是数字的总和$x$。 输入由三个整数组成$a$,$b$， 和$c$，并且输出必须列出有效解决方案的计数，然后按升序列出解决方案。 

第一个观察结果是该问题受到以下限制$x < 10^9$。 自从$x$是有界的，任何解都必须低于这个阈值。 功能$s(x)$至多是以下数字的总和$999,999,999$，即 9 乘以 9，等于 81。因此与$x$。 这是允许有效解决方案的关键观察。 

一种简单的方法，测试所有整数$10^9$会太慢了。 甚至迭代到$10^8$会导致上亿次的操作，这在1秒的时间限制内是不可能的。 

非明显的边缘情况包括计算后的负结果$b \cdot s(x) \cdot a + c$，值$x$在最上界，并且$x$数字总和的值$s(x)$为零或很小。 例如，如果$c$为负且幅度较大，可以减少$x$低于 1。如果我们天真地尝试所有数字和，我们可能会错过范围限制。 

## 方法

 暴力解决方案将迭代所有可能的解决方案$x$从 1 到$10^9$，计算数字和$s(x)$， 评价$b \cdot s(x) \cdot a + c$，并检查它是否等于$x$。 这是正确的，因为它确实测试了每个候选人的方程，但它执行了多达十亿次检查，这是不切实际的。 

关键的见解是方程可以用数字和来重写$s$而不是$x$：$$x = a \cdot b \cdot s + c$$这里，$s$必须是 1 到 81 范围内的整数，因为任何数字的最大位数之和小于$10^9$是 9 乘以 9。这一观察结果极大地减少了搜索空间。 我们只迭代最多 81 个可能的数字和，而不是迭代 10 亿个整数。 对于每个候选总和$s$，我们计算$x = a \cdot b \cdot s + c$，然后验证是否$x$等于$s$如果$x$为正且低于$10^9$。 这是有效的并且保证了正确性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(10^9) | O(10^9) | O(1) | O(1) | 太慢了 |
 | 最佳| O(81) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取整数$a$,$b$， 和$c$。 这些是方程的常数。 
2. 初始化一个空列表来存储有效的解决方案。 
3. 迭代所有可能的数字和$s$从 1 到 81。这涵盖了小于以下数字的所有可行总和$10^9$。 
4. 对于每个$s$，计算候选解$x = a \cdot b \cdot s + c$。 这直接来自于重新排列方程。 
5. 检查是否$x$为正且小于$10^9$。 丢弃该范围之外的任何值。 
6. 计算数字之和$x$并将其与$s$。 如果匹配，则追加$x$到解决方案列表。 
7. 检查所有可能的总和后，按升序对列表进行排序。 
8. 输出解的数量以及解本身。 

为什么它有效：这里的不变性是任何有效的解决方案$x$必须同时满足方程和数字和的定义。 自从$s(x)$任何一个都不能超过 81$x < 10^9$，迭代所有可能的和可以保证不会遗漏任何有效的解决方案。 检查$s(x) = s$确保候选者不会出现误报。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def digit_sum(n):
    return sum(int(d) for d in str(n))

a, b, c = map(int, input().split())
solutions = []

for s in range(1, 82):
    x = a * b * s + c
    if 0 < x < 10**9 and digit_sum(x) == s:
        solutions.append(x)

solutions.sort()
print(len(solutions))
print(*solutions)
```功能`digit_sum`将整数转换为字符串并对它的数字求和。 这对于小数字来说非常有效，并且避免了手动数字提取。 我们迭代所有可行的数字和，计算候选者，按正值和数字和进行过滤，最后排序以升序输出它们。 需要排序，因为迭代$s$不保证订单。

 ## 边缘情况

 该算法通过计算 x = a_b_s + c 来处理 c < 0。 对于 s = 1，如果 x <= 0，则将其丢弃。 例如，使用输入`1 1 -1`, x = 0 对于 s = 1 无效，因此只有 s = 2 才给出 x = 1。数字和检查可确保拒绝误报。 

例如，对于 x 接近上限`a=5, b=100000, c=0`, x = 5_100000_81 = 40500000 < 10^9，因此包含有效解。 排序可确保输出按升序排列，而不管 s 生成解决方案的顺序如何。
