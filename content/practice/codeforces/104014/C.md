 ## 解决方案
 ## 问题理解

 我们得到了一台自动售货机，里面有一系列零食包，每包都有一个名称和以卢布和戈比表示的价格。 买方也有固定金额，也以相同的格式表示。 任务是选择一个价格尽可能大但不超过买家的钱的单一零食包，附加的限制是买家必须支付准确的金额，这意味着不允许找零。 

因此，输入表示对项目列表的约束选择问题，其中每个项目都有一个数字权重（其价格），并且我们必须找到小于或等于固定预算的最大权重。 

约束的结构强烈建议采用线性扫描解决方案。 对于多达 100,000 个项目，任何对每个项目进行排序或执行重复搜索的方法在 O(N log N) 中仍然是可以接受的，但不必要的开销是可以避免的，因为我们只需要一个最佳候选者。 这立即排除了任何二次方，例如成对比较或嵌套扫描。 

问题的一个微妙部分是解析货币格式。 值以“R,cc”等字符串形式给出，其中卢布和科比必须标准化为单个整数值。 粗心的实现可能会按字典顺序比较字符串，或者在没有适当规范化的情况下分别比较卢布和科比，从而导致排序不正确。 

一些边缘情况很重要：

 一种极端情况是没有商品买得起。 例如，如果预算为 10,00，并且所有项目的成本都超过该值，则正确的输出为“-1”。 错误地初始化最佳候选的简单解决方案（例如，使用索引 0 而不检查可负担性）将错误地返回无效的零食。 

另一个边缘情况是多个商品具有相同的最高可承受价格。 例如，如果两件商品的成本均为 50,00，并且预算为 50,00，则任一商品均有效。 有缺陷的实现可能会根据比较逻辑覆盖或跳过有效的候选者，但任何稳定的“取最大值≤预算”逻辑都有效。 

最后一个极端情况是价格非常接近预算，尤其是在 99.99 戈比和 100.00 戈比之间。 不正确的戈比解析可能会使比较结果改变 100 倍，并悄悄地破坏正确性。 

## 方法

 蛮力的想法很简单：将所有价格转换为一个整数单位，然后扫描每个项目并检查其价格是否在预算范围内。 如果是，则将其与迄今为止找到的最佳候选者进行比较并保留最大值。 

这是可行的，因为问题简化为在约束下找到最大元素。 然而，任何更复杂的策略（例如排序）都是不必要的，因为我们不需要超出单个最大可行值的排序。 

蛮力方法已经以 O(N) 的速度运行，这在渐近复杂度方面是最优的。 没有像前缀和或组合数学这样的隐藏结构； 每个项目都是独立的。 与天真的尝试相比，唯一真正的改进是货币价值的谨慎正常化。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力扫描| O(N) | O(1) | O(1) | 已接受 |
 | 排序然后扫描 | O(N log N) | O(N log N) | O(N) | 已接受但没有必要 |

 ## 算法演练

 我们将所有货币值转换为代表总戈比的整数，然后在跟踪最佳有效候选者的同时对这些项目执行一次传递。 

1. 将预算字符串解析为卢布和科比，然后以科比计算总预算：`budget = R * 100 + cc`。 这确保了所有项目的统一比较。 
2.初始化两个变量：`best_price = -1`和`best_name = ""`。 哨兵`-1`保证任何有效的物品都会取代它。 
3. 对于每个零食包，将其价格字符串解析为相同的整数格式。 此步骤必须与预算转换相同，以保持正确性。 
4. 检查零食价格是否小于或等于预算。 如果不是，请完全跳过它，因为不找零就无法购买。 
5. 如果零食价格实惠且价格大于`best_price`，更新两者`best_price`和`best_name`与此项目。 这种贪心更新之所以有效，是因为我们只关心最大可行值。 
6.处理完所有项目后，输出`best_name`如果至少更新过一次，否则输出“-1”。 

### 为什么它有效

 在扫描的每一步中，`best_price`迄今为止见过的最大实惠价格的商店。 因为我们仅在遇到严格更大的有效值时才更新它，所以它始终是已处理前缀的最大值。 当扫描结束时，前缀是整个数组，因此存储的值是预算约束下的全局最大值。 未来的操作不会使之前的比较无效，因为所有项目都是独立的并且没有副作用。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def parse_money(s):
    # format: R,cc
    r, cc = s.strip().split(',')
    return int(r) * 100 + int(cc)

n, budget_str = input().split()
n = int(n)
budget = parse_money(budget_str)

best_price = -1
best_name = ""

for _ in range(n):
    parts = input().split()
    name = parts[0]
    price = parse_money(parts[1])

    if price <= budget and price > best_price:
        best_price = price
        best_name = name

print(best_name if best_price != -1 else -1)
```解决方案的核心是`parse_money`函数，它将所有值标准化为单个可比较的整数。 如果没有此步骤，比较混合卢布-科比值将需要字典或元组逻辑，这在手动实现下更容易出错。 

扫描会保留一个最佳候选者，仅在找到严格更实惠的价格时才更新。 这确保了正确性，而不需要排序或额外的数据结构。

 ## 边缘情况

 一种重要的边缘情况是所有物品都比预算贵。 例如，预算为 10,00，项目为 20,00 和 30,00，算法永远不会更新`best_price`，保持在-1。 输出正确地变为“-1”，因为没有选择有效的候选者。 

另一种边缘情况发生在完全相等的情况下。 如果预算为 50,00 并且某件商品的成本恰好为 50,00，则条件`price <= budget`确保它被接受。 扫描更新`best_price`除非后来出现相同或更大的有效项，否则这将成为最终答案。 

第三个边缘情况是解析正确性。 对于像 0.05 这样的输入，如果未能将科比填充或解释为两位数的值，则会将其视为 5 而不是 0.05 卢布，从而破坏比较。 整数标准化为戈比可确保 0,05 一致地变为 5，并且比较保持正确。
