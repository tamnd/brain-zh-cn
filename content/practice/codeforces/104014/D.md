 ## 解决方案
 ## 问题理解

 我们得到一个由多个单词组成的文本，每个单词都应该遵循虚构语言的简单语音规则。 如果一个单词在此语言定义下是“名词”或“动词”，则该单词是有效的。 动词是仅由元音组成的任何非空序列。 名词是任何非空序列，其中字母在元音和辅音之间严格交替。 

任务不是以语义方式完全重建或重新分类单词，而是最小程度地修改文本，以便每个单词在这些规则下变得有效。 修改意味着将一个字符更改为另一个小写拉丁字母。 每个更改的字符都算作一个错误，并且我们希望所有单词的字符更改总数最少。 

关键的结构观察是单词是独立的。 修复一个单词的成本不会影响另一个单词，因此全局答案只是每个单词的最佳成本之和。 

输入大小使得这一点变得很重要。 最多可以有 10^5 个单词，所有单词的字符总数可以达到 10^6。 任何解决方案即使对每个字进行二次工作也是不可能的。 甚至每个单词的 O(n^2) 也远远超出了限制。 预期的解决方案必须在 O(1) 工作中处理每个字符，给出总线性 O(总长度)。 

一个幼稚的误解来自于试图“尝试所有替换”或“猜测一个词应该是名词还是动词，然后进行局部调整”。 在微妙的情况下这可能会失败。 

例如，考虑这个词`"abc"`。 如果我们选择名词结构，我们必须交替元音-辅音-元音或辅音-元音-辅音。 如果我们选择动词结构，我们必须将其全部转换为元音。 粗心的贪婪方法可能只转换一些字母而不全局检查这两种模式，从而导致编辑计数不理想。 

另一个边缘情况是单字母单词，例如`"b"`。 它既可以作为名词（单字母空洞地交替）也可以作为动词（仅单元音）。 幼稚的方法可能会错误地强制进行更改。 

## 方法

 暴力方法将独立处理每个单词，并尝试将其转换为相同长度的每个可能的有效单词。 对于长度为 L 的单词，有 26^L 种可能性，甚至限制为元音或辅音模式仍然留下字母分配的指数组合。 即使我们只修复结构模式并计算不匹配，粗暴的想法也会变成：尝试所有可能的交替模式和全元音模式，计算每个模式的编辑距离，并取最小值。 

原则上这是正确的，因为任何最终有效单词都必须与这些结构模板之一匹配。 然而，它太慢了，因为对于每个单词，我们都会重复地重新扫描字符以进行多个模式检查，如果天真地跨所有模式变化进行，它会退化为二次或更糟糕的行为。 

关键的见解是有效单词的结构极其有限。 只有两种模式类型：

 首先，动词模式，其中每个字符都必须是元音。 

其次，名词模式，其中每个位置都有一个固定的所需类型，仅取决于奇偶性：从元音开始的元音-辅音-元音-辅音，或者从辅音开始。 这正好给出了两个交替模板。 

对于每个单词，我们只需要计算与这三个候选词的匹配成本：全元音、从元音开始交替、从辅音开始交替。 每个成本都可以在一次线性扫描中计算出来。 其中最好的是这个词的答案。 

这将问题从“搜索字符串”减少为“评估三个确定性模板”。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解所有转换 | 指数| O(1) | O(1) | 太慢了 |
 | 检查每个单词 3 个结构模板 | O（总长度）| O(1) | O(1) | 已接受 |

 ## 算法演练

 我们独立处理每个单词并计算三个成本。 

1. 定义一个辅助谓词来检查字符是否为元音。 元音集是 {a, e, i, o, u, y}。 这允许每个字符进行 O(1) 分类。 
2. 对于给定的单词，计算 cost_vowel，即该字符不是元音的位置数。 这是将整个单词转换为动词的成本。 推理是每个非元音都必须变成元音，并且每个元音都已经有效。 
3. 计算cost_alt0，即使以元音开头的单词交替出现的成本。 对于位置 i，如果 i 是偶数，则目标必须是元音，否则是辅音。 每个不匹配都会导致成本增加 1。 
4. 计算cost_alt1，即使单词以辅音开头交替的成本。 对于位置 i，如果 i 是偶数，则目标是辅音，否则是元音。 再次计算不匹配的情况。 
5. 取三个成本中的最小值并将其添加到全局答案中。 
6. 将所有单词的结果相加并输出。 

关键的实现细节是我们从不修改字符串。 我们只计算不匹配的情况，这使解决方案保持线性并避免不必要的分配。 

### 为什么它有效

 任何有效的最终单词必须完全符合三种结构形式之一：所有元音或以元音开头交替或以辅音开头交替。 对于任何固定的目标结构，将单词转换为该结构的最小编辑次数正是不匹配位置的数量，因为每个字符都可以独立更改以匹配其所需的类型。 由于这三种结构详尽地涵盖了所有有效定义，因此对它们取最小值即可产生全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

VOWELS = set("aeiouy")

def solve():
    n = int(input())
    words = input().split()
    
    ans = 0
    
    for w in words:
        cost_vowel = 0
        cost_alt0 = 0
        cost_alt1 = 0
        
        for i, ch in enumerate(w):
            is_vowel = ch in VOWELS
            
            # all vowels
            if not is_vowel:
                cost_vowel += 1
            
            # alternating starting with vowel
            if i % 2 == 0:
                if not is_vowel:
                    cost_alt0 += 1
                if is_vowel:
                    cost_alt1 += 1
            else:
                if is_vowel:
                    cost_alt0 += 1
                if not is_vowel:
                    cost_alt1 += 1
        
        ans += min(cost_vowel, cost_alt0, cost_alt1)
    
    print(ans)

if __name__ == "__main__":
    solve()
```该实现一次读取所有单词并在单个循环中对字符进行处理。 元音检查是使用一组的恒定时间。 

交替逻辑纯粹通过索引奇偶校验来处理。 偶数索引对应于第一个模式开始，奇数索引相应地跟随。 这避免了任何字符串转换或辅助数组。 

一个微妙的点是 cost_alt0 和 cost_alt1 在一次传递中同时计算。 这避免了每个单词扫描三次。

 输入：```

```为了`"a"`，所有结构成本为 0。 

对于`"bcd"`:

 所有元音成本都是 3。

 ## 边缘情况

 像这样的单字母词`"b"`证明所有三个结构可以重叠。 该算法根据奇偶校验规则计算 cost_vowel = 1、cost_alt0 = 0 或 1，并且 cost_alt1 类似，因此当有效结构无需编辑即可匹配时，最小值正确地变为 0。 

完全辅音的字符串，例如`"bcdfgh"`迫使解决方案依赖于交替模式。 仅元音转换成本高昂，并且仅基于奇偶校验的校正只能产生最少的编辑。 扫描可以正确计算不匹配情况，无需进行任何全局重组。 

一个完整的元音字符串，例如`"aeiouy"`显示了动词模式占主导地位的相反情况。 两种交替模式都会引入不必要的不​​匹配，并且算法正确地选择了全元音选项。
