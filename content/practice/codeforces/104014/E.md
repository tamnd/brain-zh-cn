 ## 解决方案
 ## 问题理解

 我们给出了项目的最终版本号，写为正整数$N$。 该项目按照一个固定的规则逐月演变：如果当前版本有$k$数字，然后一个月后它增加的数字包括$k$那些。 例如，5 位版本增加$11111$下个月，3位数版本增加$111$， 等等。 

任务不是模拟正向，而是重建可能导致给定数字的最长可能历史$N$。 该历史记录中的第一个版本可以是任何正整数，并且每次转换必须遵守增量取决于当前状态的数字长度的规则。 我们想要最大可能的月份数，包括当前的月份数。 

关键的难点在于增量取决于当前版本的位数，而不是固定的常数。 这意味着这个过程不是一个简单的算术级数，并且反转它也不是直截了当的。 

约束条件$N \le 10^{18}$意味着所有中间值都适合 64 位整数。 任何试图天真地探索所有可能历史的方法都会呈指数级爆炸，因为原则上每个状态都可能有多个可能的前身。 

数字长度转换会产生微妙的边缘情况。 例如，在 999 和 1000 之间移动会更改位数，从而更改下一步中的增量大小。 如果我们在逆向过程时忽略数字约束，我们可能会构建不满足前向规则的无效历史。 

## 方法

 一个直接的想法是向后模拟$N$。 如果我们处于一个值$x$，我们尝试猜测之前的值$y$。 如果$y$有$k$数字，那么前向过渡是$y + R_k = x$， 在哪里$R_k = 111\ldots1$（k 位）。 这样我们就可以计算候选人$y = x - R_k$对于所有可能的数字长度$k$，然后检查是否是这样$y$是有效的。 

这种强力反向步骤在本地是正确的：每个有效的先前状态都必须出现在这些候选者中。 然而，分支所有可能的$k \in [1, 18]$在最坏的情况下，递归地探索所有链会导致一个大的搜索树。 尽管深度因数值缩小而受到限制，但不同的选择$k$可能会导致不同的历史，而我们想要最大的长度，所以贪心选择显然并不安全。 

关键的观察结果是，就传出转换而言，状态空间很小。 每个数字最多有 18 个有效前驱，每个前驱由下式唯一确定：$k$。 这允许我们将过程视为有向图，其中每个节点都是一个数字，边指向有效的先前状态。 由于值沿边缘严格递减，因此不存在循环，我们可以使用记忆 DFS 计算最长路径。 

问题归结为找到最长的链结束于$N$在 DAG 中，每个节点最多分支为 18 个由数字长度约束定义的前驱节点。

 ## 算法演练

 ### 1. 定义重新单位值

 对于每个可能的数字长度$k$, 预计算$R_k = 111\ldots1$。 这可以有效地计算为$(10^k - 1)/9$。 

这为我们提供了一种直接的方法来测试一个数字是否可以来自先前的状态$k$数字。 

### 2.定义反向转换

 对于当前值$x$，我们尝试所有可能的数字长度$k$。 我们计算候选前任：$$y = x - R_k$$如果前一个数字恰好具有，则这表示唯一可能的前一个值$k$数字。 

### 3. 验证候选人

 候选人$y$仅当满足两个条件时才有效。 

首先，它必须是正数并且位于$k$- 数字：$$10^{k-1} \le y \le 10^k - 1$$其次，必须保持向前一致：$$y + R_k = x$$如果我们构建，第二个条件在代数上始终为真$y$正确，所以真正的约束是数字长度的一致性。 

### 4. 使用 DFS + 记忆计算最佳链

 我们定义一个函数$f(x)$作为结束于的最大步数$x$。 然后：$$f(x) = 1 + \max f(y)$$超过所有有效的前任$y$。 

如果没有有效的前任，$f(x) = 1$。 

记忆化确保每个值都被计算一次。 

### 5.返回答案

 最终的答案是$f(N)$，表示以给定版本结束的最长可能历史记录。 

### 为什么它有效

 每个有效的历史记录必须对应于一系列有效的反向转换，并且每个反向转换完全由数字长度的选择决定。 由于每次转换都会严格减少数字的大小，因此状态图是非循环的。 因此，记忆递归可以准确计算该 DAG 中的最长路径，因为所有可能的前驱路径都得到了最佳探索和重用。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1000000)

from functools import lru_cache

def repunit(k):
    return (10**k - 1) // 9

pow10 = [1]
for _ in range(20):
    pow10.append(pow10[-1] * 10)

@lru_cache(None)
def dfs(x):
    best = 1
    for k in range(1, 19):
        r = repunit(k)
        y = x - r
        if y <= 0:
            continue
        if pow10[k-1] <= y <= pow10[k] - 1:
            best = max(best, 1 + dfs(y))
    return best

def main():
    n = int(input().strip())
    print(dfs(n))

if __name__ == "__main__":
    main()
```该实现直接对递归进行编码。 这`repunit(k)`函数有效地构建增量模式。 这`pow10`数组用于在常数时间内强制执行数字长度约束。 

DFS 探索所有可能的有效前驱并记住结果，因此每个数字仅处理一次。 递归深度仍然很小，因为每一步都会显着降低幅度。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |

 | 空间|$O(\text{states})$| 记忆表将每个可到达的数字存储一次 |

 ## 边缘情况

 一个关键的边缘情况是减法导致数字长度变化。 例如，从 4 位数字开始可能会产生 3 位前任数字，这会更改下一步中的增量规则。 该算法通过显式检查每个候选者的数字限制来处理这个问题$k$，确保仅考虑有效长度的前趋。 

另一种边缘情况发生在十的幂附近。 例如，像 1000 或 10000 这样的值可以有比前一个数字短一位数或长度相等的值，具体取决于$k$。 DFS 不假设数字长度的连续性并独立评估所有可能性。 

最后一种情况是非常小的数字，不存在前驱。 在这种情况下，DFS 正确返回 1，表示长度为 1 的历史记录仅包含当前版本。
