 ## 解决方案
 ## 问题理解

 棋盘是一个包含空格子、黑色棋子和白色棋子的战场。 我们可以选择一颗白色棋子作为控制棋子。 游戏过程中，该棋子一次只能向上移动一行，选择同一列、左对角线或右对角线。 它不能进入​​被另一个白色棋子占据的单元格。 每当它到达黑色棋子时，该棋子就会被摧毁。 目标是选择起始白子及其移动路径，使得被消灭的黑子数量尽可能多。 

输入描述了板的尺寸，后面跟着网格本身。 输出是一个整数，即一条有效向上路径可以访问的黑色单元的最大数量。 

电路板尺寸最多为 50 x 50，因此只有 2500 个单元。 这个值足够小，使得探索每个细胞状态的解决方案成为可能。 然而，显式地尝试每个可能的路径仍然是昂贵的，因为可能的路径的数量随着行数呈指数增长。 处理每个单元一次的动态编程解决方案是预期的复杂性。 

运动方向创建了问题的主要结构。 由于每次移动都会减少行索引，因此可能的移动图没有循环。 这意味着每个单元格都可以从其下面的单元格进行评估，而不需要更复杂的图形算法。 

一些边缘情况可能会破坏粗心的实现。 顶行的单个白色棋子已经具有零步的有效路径。 例如：```
Input
1 1
W

Output
0
```假设每个白色棋子必须至少移动一次的解决方案在这里可能会失败。 

必须计算起始位置正上方的黑色棋子，因为移动到其中会破坏它。 例如：```
Input
2 1
W
B

Output
1
```仅计算移动后的单元格而不包括目标单元格的错误将返回零。 

另一个常见的错误是允许移动穿过另一块白色棋子。 考虑：```
Input
3 1
W
W
B

Output
0
```上面的白色块无法穿过下面的白色块，因此黑色单元格不可达。 将白细胞视为空细胞会错误地返回一个。 

## 方法

 直接的方法是模拟每个白棋的每个可能的运动序列。 路径从一个白色单元格开始，并分支为每行最多三个可能的下一个单元格。 这种方法是正确的，因为会检查每条可能的路线，并且可以选择具有最多黑色单元的路线。 问题是路线数量呈指数级增长。 在有 50 行的棋盘中，单个棋子最多可以有$3^{49}$在考虑障碍物之前可能的运动顺序，这远远超出了我们可以探索的范围。 

有用的观察是许多不同的路径到达同一个单元格。 一旦受控部件到达特定单元，从该点开始的最佳未来结果并不取决于到达它所使用的路径。 唯一重要的信息是当前位置。 这使得该问题成为有向无环图上的最长路径问题。 

我们可以定义`dp[i][j]`作为从单元格开始可以破坏的最大黑色块数`(i, j)`并继续向上。 从一个单元格中，我们尝试上面一行中的三个可能的单元格。 如果目的地是一块白色的棋子，那么这种过渡是不可能的。 如果目的地是黑色，我们获得一分并从那里继续。 因为每次转换都会进入较小的行索引，所以我们可以从板顶部向下计算值或使用带有记忆的递归。 

暴力法会失败，因为它重复解决相同的子问题。 动态编程解决方案将这些结果存储一次并重复使用它们。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 最坏情况下的 O(3^n) | O(n) 递归深度 | 太慢了|
 | 最佳 | O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 1. 创建一个记忆函数，返回从给定单元格中可获得的最佳黑色块数。 

该函数从该位置代表了游戏的整个未来。 由于所有移动都是向上的，因此每个递归调用都会靠近板的末端。 
2. 对于单元格，考虑到上一行的三种可能的移动：左上、上和右上。 

每个有效目的地代表当前路径的一个可能的延续。 
3. 忽略离开棋盘或进入另一个白子的着法。 

白色块会永久阻止移动，因此将其视为正常单元格会创建无效路径。 
4. 对于每个有效目的地，如果该目的地包含黑色棋子，则添加一个，然后添加该目的地的最佳结果。 

当前移动是获得目标单元格值的唯一机会，因为路径永远不会返回。 
5. 从每一个白块开始计算，取最大的结果。 

玩家可以选择任何初始白棋，因此全局答案是所有可能开始中的最佳值。 

为什么它有效：动态规划不变量是`dp[i][j]`始终存储可以从单元中销毁的最大数量的黑色棋子`(i, j)`向前。 该值是正确的，因为每个合法的第一个移动都会被检查，并且在该移动之后，剩余的问题与目标单元格的问题类型完全相同。 由于移动总是移至较小的行，因此不存在循环依赖性，因此计算出的最大值不会因稍后的选择而失效。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    board = [input().strip() for _ in range(n)]

    sys.setrecursionlimit(1000000)
    memo = [[-1] * m for _ in range(n)]

    def dfs(r, c):
        if memo[r][c] != -1:
            return memo[r][c]

        best = 0
        nr = r - 1

        if nr >= 0:
            for dc in (-1, 0, 1):
                nc = c + dc
                if 0 <= nc < m and board[nr][nc] != 'W':
                    gain = 1 if board[nr][nc] == 'B' else 0
                    best = max(best, gain + dfs(nr, nc))

        memo[r][c] = best
        return best

    ans = 0
    for i in range(n):
        for j in range(m):
            if board[i][j] == 'W':
                ans = max(ans, dfs(i, j))

    print(ans)

if __name__ == "__main__":
    solve()
```输入被读取为字符网格，因为每个单元格类型直接影响转换规则。 记忆表使用`-1`作为未计算的标记，因为有效答案始终是非负的。 

递归函数首先检查当前单元格是否已被处理。 如果没有这种检查，许多路径将重复计算相同的未来状态。 

转换循环检查前一行中的三列。 边界检查防止无效的列访问，白单元检查强制执行阻止规则。 在递归调用之前添加黑单元贡献，因为移动发生时目标单元被破坏。 

最后的循环会尝试所有可能的起始白色棋子。 一个常见的错误是只从最低的白色棋子开始，但问题是允许任何白色棋子，包括靠近顶部的白色棋子。

 ## 边缘情况

 对于顶排白色件案例：```
Input
1 1
W
```该算法调用`dfs(0,0)`。 上面没有行，因此该值保持为零。 答案正确地保持为零，因为所选的棋子不能破坏任何东西。 

对于正上方的黑色部分：```
Input
2 1
W
B
```起始单元格是`(0,0)`在从零开始的索引中。 唯一的转变到达黑色单元，增益为 1。 该目的地的递归结果为零，因为它现在位于顶行。 最终的答案是`1`。 

对于白色阻滞剂：```
Input
3 1
W
W
B
```上面的白色棋子检查唯一可能的移动并看到另一个白色棋子，因此跳过了转换。 下面的白色棋子只有下面的黑色单元格，但运动只是向上，所以它无法到达那个黑色单元格。 答案依然存在`0`。 

这些情况由转换规则自然地处理：仅考虑合法的向上移动，并且在影响动态编程结果之前排除每个阻塞或不可达的单元。
