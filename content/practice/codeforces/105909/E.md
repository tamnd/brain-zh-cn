 ## 解决方案
 ## 问题理解

 游戏由一系列 Boss 组成。 玩家以完全健康的状态开始每次尝试，并需要按顺序击败所有头目。 失去所有生命值或立即被头目杀死会结束当前的尝试，玩家必须从头开始。 在每击败固定数量的 Boss 后，可能会出现一个检查点，使玩家恢复完全健康。 

对于每个老板来说，立即被杀死的几率取决于已经损失的生命值。 如果玩家输了`j`生命值，即时死亡概率为基础概率乘以`x^j`。 如果玩家幸存，他们可能会再失去 1 点生命值。 任务是找到清除整个序列所需的预期完整尝试次数。 

输入给出了 Boss 的数量、初始生命值、检查点间隔、增长因子`x`，以及每个老板的概率。 输出是预期的尝试次数模数`10^9 + 7`。 

从约束中得到的重要观察结果是`n`和`h`两者都可以大到`5 * 10^4`。 对每个老板和每个可能的健康值的直接DP将有大约`2.5 * 10^9`州，这太多了。 我们需要利用这样一个事实：受到伤害后立即死亡的概率呈指数级增长。 

一旦失去足够的生命值，即使是最安全的 Boss 也会以 1 的概率杀死玩家。因为最小的即时杀死概率至少为`1%`和`x`至少是`1.01`，有用的健康受损状态的数量只有几百个。 这极大地减少了动态编程状态空间。 

有几种很容易被忽略的边缘情况。 如果没有检查点，伤害会在整个战斗中累积。 例如，输入：```
1 2 0 150
0
50
```Boss 有概率在生命值满时杀死`0.5`，如果玩家幸存，则没有伤害机会。 成功概率为`0.5`，所以答案是`2`。 在每个 Boss 后意外重置的解决方案仍然会通过许多测试，但在存在多个 Boss 时会失败。 

另一种情况是检查点刚好出现在 Boss 之后。 例如：```
2 2 1 150
60 60
50 50
```击败第一个 Boss 后，检查站会先于第二个 Boss 恢复生命值。 成功概率为`0.5 * 0.5 = 0.25`，所以答案是`4`。 如果我们保留受损状态而不是重置它，我们就会错误地认为第二个 Boss 更难。 

最后一个棘手的情况是伤害会使生命值降至零。 例如：```
1 1 0 150
25
50
```玩家有概率在即时死亡检查中幸存`0.5`，但随后失去 1 点生命值并立即失败。 成功概率为`0.5 * 0.75 = 0.375`，给出答案`8/3`对所需素数取模。 忽略健康零故障会产生错误的结果。 

## 方法

 最直接的方法是模拟每一种可能的生命损失量。 让`dp[i][j]`表示击败第一个后还活着的概率`i`老板们与`j`失去了健康。 对于每个老板，我们都会尝试两种结果：生存并受到伤害，或者生存而不受到伤害。 这种转变是正确的，因为下一个 Boss 所需的唯一信息是当前的伤害量。 

问题在于状态空间的大小。 可以有`n = 50000`老板和`h = 50000`可能的损坏值，导致`2.5 * 10^9`过渡。 在期限内这是不可能的。 

关键的观察是大的伤害值永远没有用处。 如果玩家失去过多的生命值，下一个boss就会以1的概率杀死他们。由于死亡概率呈指数级增长，所以最大有用的伤害值只有几百左右。 

我们可以压缩 DP 以仅存储可达到的有用伤害量。 过渡保持不变，但现在第二维受到一个小常数的限制。 在每个检查点之后，所有活着的状态都会合并到完全健康状态，因为玩家已经痊愈了。 

预期尝试次数是一次尝试成功概率的倒数。 如果成功概率为`p`，独立尝试的预期次数是`1 / p`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(nh) | O(h) | 太慢了 |
 | 具有压缩健康状态的最佳 DP | O(nC) | O(C)| 已接受 |

 这里`C`是最大有用伤害计数，在给定限制下低于 500。 

## 算法演练

 1. 计算仍然存在的损坏状态的最大数量。 我们只保留即使是最安全的 Boss 也无法保证立即死亡的伤害值。 任何更大的值永远无法促成成功的运行。 
2.维护一个DP数组，其中`dp[j]`存储活着到达当前老板的概率`j`失去了健康。 最初玩家处于完全健康状态，所以`dp[0] = 1`。 
3.一一处理boss。 对于一个状态`j`失去生命值，计算在即时杀死检查中幸存的概率。 生存概率为`1 - p_i * x^j`。 
4.如果玩家幸存并且Boss没有造成伤害，则状态保持相同的伤害量。 
5.如果玩家幸存并受到伤害，则伤害量增加1。 仅当新的生命值仍然为正并且新的伤害量是有效的存储状态时才允许此转换。 
6. 处理完作为检查点边界的 boss 后，将每个生存状态概率重新添加到`dp[0]`，因为所有成功的进展都再次达到完全健康。 
7. 在最后一个boss之后，将所有剩余的概率相加。 这是完成一次尝试的概率。 答案是该概率的模逆。 

为什么它有效：DP 不变量是在处理完任何 Boss 前缀后，`dp[j]`准确地表示在该前缀之后还活着的概率`j`自上次检查点以来失去了生命值。 转换枚举了下一个 Boss 的所有可能结果，并且检查点操作精确地合并了修复后变得相同的状态。 由于损害太大的国家对未来成功做出贡献的机会为零，因此删除它们不会改变最终的概率。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, h, k, x0 = map(int, input().split())
    q0 = list(map(int, input().split()))
    p0 = list(map(int, input().split()))

    inv100 = pow(100, MOD - 2, MOD)
    x = x0 * inv100 % MOD

    # Compute the maximum useful damage states.
    mn = min(p0)
    limit = 0
    cur = mn
    while cur * x0 < 100:
        cur = cur * x0
        limit += 1
    limit += 1
    limit = min(limit, h)

    dp = [0] * limit
    dp[0] = 1

    for i in range(n):
        ndp = [0] * limit
        for j in range(limit):
            if dp[j] == 0:
                continue

            death = p0[i] * pow(x, j, MOD) % MOD * inv100 % MOD
            survive = (1 - death) % MOD

            if survive == 0:
                continue

            no_damage = (100 - q0[i]) * inv100 % MOD
            damage = q0[i] * inv100 % MOD

            ndp[j] = (ndp[j] + dp[j] * survive % MOD * no_damage) % MOD

            if j + 1 < limit:
                ndp[j + 1] = (ndp[j + 1] + dp[j] * survive % MOD * damage) % MOD

        dp = ndp

        if k != 0 and (i + 1) % k == 0:
            total = sum(dp) % MOD
            dp = [0] * limit
            dp[0] = total

    success = sum(dp) % MOD
    print(pow(success, MOD - 2, MOD))

if __name__ == "__main__":
    solve()
```输入被直接读取为整数，因为每个概率都以整数百分比给出。 我们通过乘以以下函数的倒数将概率转换为模分数`100`。 

这`limit`计算是主要的优化。 一旦保证即时死亡概率至少为 1，我们就停止，而不是存储所有可能的健康损失。 循环很小，因为增长因子至少为`1.01`。 

转换首先应用生存概率。 生存后两种可能的结果是失去 1 点生命值或保持相同的生命值。 条件`j + 1 < limit`是必要的，因为超出有用范围的状态永远无法到达终点。 

检查点处理是在完成Boss后完成的。 当前的概率是相加的，因为一旦治愈，所有健康损失状态都会变得相同。 

通过问题保证，最终概率永远不会为零，因此模逆存在。 预期尝试次数是一次尝试成功概率的倒数。 

## 工作示例

 对于一个简单的情况：```
1 1 0 150
25
50
```唯一拥有全生命值死亡概率的 Boss`0.5`。 踪迹是：

 | 老板| 损坏状态| 之前的概率 | 生存| 结果 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 1/2 | 1/2 损害 1 点生命值，失败 |

 玩家有一半的时间能在击杀检查中幸存，但失去一个生命值会使生命值为零，因此成功概率为`0.5 * 0.75 = 0.375`。 最终的 DP 总和是一次成功运行的概率，其倒数给出了预期的尝试次数。 

对于检查点情况：```
2 2 1 150
60 60
50 50
```踪迹是：

 | 老板| 状态| 行动| 概率|
 | --- | --- | --- | --- |
 | 1 | 0 伤害 | 生存老板| 0.5 | 0.5
 | 1 | 1 伤害 | 检查点重置| 合并为0伤害|
 | 2 | 0 伤害 | 生存老板| 0.5 | 0.5

 在第一个boss之后，每一条成功的道路都会被治愈。 两个boss是独立的全生命值战斗，所以成功概率为`0.25`，给出答案`4`。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(nC) | 每个 boss 只更新压缩伤害状态 |
 | 空间| O(C)| 仅存储当前和下一个 DP 数组 |

 价值`C`受死亡概率的指数增长限制，并且最大约束低于几百。 因此，该解决方案仅执行几百万次操作，完全符合限制。

 ## 边缘情况

 第一个边缘情况是没有检查点。 DP 永远不会将各州合并回完全健康状态，因此伤害会贯穿整个战斗。 这符合游戏规则，因为玩家只能在检查点进行治疗。 

第二个边缘情况是紧邻 Boss 之后的检查点。 算法在处理完那个 Boss 之后重置，而不是之前。 这很重要，因为在治疗发生之前仍然必须击败 Boss。 

最后一个边缘情况是健康状况达到零。 民主党从不创建一个国家`h`失去健康，因为这种状态代表失败，所以这些路径会自动消失。 这可以防止计算玩家在技术上幸存下来的即时杀死检查但死于所造成的伤害的尝试。
