 ## 解决方案
 ## 问题理解

 我们有一张圆桌`n`玩家。 玩家`i`开始于`a[i]`牌。 游戏从玩家1开始，初始方向为顺时针方向。 

恰好是一个序列`m`给出了打出的牌。 每个角色描述了该回合打出的牌：`C`是普通卡牌，没有任何效果。`S`跳过当前方向的下一个玩家。`R`反转播放方向。`D`给下一个玩家两张额外的牌，并跳过该玩家。 

每当玩家打出一张牌时，他们的手牌大小就会减少一手。 如果他们的手牌在玩完后立即为零，他们将立即离开游戏并被移出圆圈。 

输入保证游戏顺序有效，并且在最终游戏后至少有两名玩家仍然有牌。 我们必须输出每个原始玩家最终持有的牌数。 

有趣的是，玩家在模拟过程中消失了。 一旦有人离开，未来的回合顺序、跳过、反转和抽两效果必须对剩余的活跃玩家循环列表起作用。 

限制可达`2 × 10^5`球员和`2 × 10^5`打牌。 重复扫描圆圈以找到下一个活跃玩家的模拟可能会降低到二次时间。 对于 200,000 次操作，我们需要在恒定或对数时间内处理每一轮。 

当玩家打出一张特殊牌后立即离开时，会出现微妙的边缘情况。 

例如：```
3 players
cards = [1, 5, 5]
play = "S"
```玩家 1 上场`S`，他们的牌数变为零，然后他们离开。 跳过的玩家仍然是玩家 2，因为“下一个玩家”是根据玩家 1 消失之前的位置确定的。 如果不小心实施，首先删除玩家 1，然后搜索下一个玩家，可能会瞄准错误的人。 

另一个棘手的情况是离开的玩家打出的反向牌。```
3 players
cards = [1, 5, 5]
play = "R"
```玩家 1 玩完后立即离开。 方向改变，下一回合属于新方向上位于玩家 1 对面的玩家。 如果我们尝试从被移除的玩家继续，而不保留其邻居，模拟就会中断。 

错误的最后一个来源是将删除与跳过相结合。```
3 players
cards = [1, 5, 5]
play = "D"
```玩家 1 给玩家 2 两张牌，玩家 2 失去回合，玩家 1 离开，下一回合成为玩家 3。这些更新的顺序很重要。 

## 方法

 最直接的模拟将所有活跃玩家存储在一个圆圈中，并在每张牌之后遍历玩家以查找下一个行动的人。 这是正确的，因为游戏规则是本地的，每个回合只影响当前方向附近的玩家。 

问题是效率。 玩家可能会离开游戏，这意味着我们需要将他们从圈子中删除。 如果我们用正常的数组或列表来表示活跃玩家，那么删除某人可能会花费`O(n)`。 这样做直到`m = 2 × 10^5`次导致大约`O(nm)`工作，远远超出了极限。 

关键的观察是游戏只需要对活跃玩家进行三个操作：

 1. 寻找下一个活跃玩家。 
2. 找到之前的活跃玩家。 
3. 从圈子中移除一名玩家。 

这些正是循环双向链表所支持的操作`O(1)`时间。 

我们为每个玩家存储其当前的顺时针邻居和逆时针邻居。 删除玩家成为标准的链表拼接。 之后，所有效果都可以仅使用邻居指针来处理。 

每张打出的牌只需要恒定数量的指针更新和手数更新，从而给出线性的总复杂度。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(纳米) | O(n) | 太慢了 |
 | 最佳 | O(n + m) | O(n) | 已接受 |

 ## 算法演练

 1. 将每个玩家的牌数存储在一个数组中。 
2. 使用两个数组构建循环双向链表：`nxt[i]`是玩家的顺时针邻居`i`,`prv[i]`是玩家的逆时针邻居`i`。 
3.让`cur = 1`，因为玩家 1 首先移动。 
4.让`dir = 1`代表顺时针方向和`dir = -1`代表逆时针方向。 
5. 对于播放字符串中的每个字符：

 1. 在任何移除之前记录当前玩家的两个邻居：`left = prv[cur]`,`right = nxt[cur]`。 
2. 如果该卡是`S`或者`D`，确定受影响的玩家：`target = right`什么时候`dir = 1`,`target = left`什么时候`dir = -1`。 
3. 如果该卡是`D`，添加两张卡到`target`。 
4. 减少`cards[cur]`由于该牌已打出，因此加一。 
5. 如果`cards[cur]`变为零，删除`cur`从链接列表中。 
6.处理卡牌效果。 

为了`C`，下一个玩家就是`target`。 

为了`S`和`D`, 下一个玩家是之后的玩家`target`在当前的方向上。 

为了`R`，反转方向。 下一个玩家成为新方向上当前位置的邻居。 
6. 继续，直到所有`m`卡已处理。 
7. 输出每位玩家最终的牌数。 

### 为什么它有效

 链表始终准确地代表仍然持有牌的玩家。 当玩家的计数达到零时，他们会立即被移除，符合规则。 

对于每个回合，该算法都会在选择任何未来回合之前使用当前圆圈和当前方向来识别受影响的玩家。 这符合“下一个玩家”的游戏定义。 

不变的是在处理每张牌之前，`cur`正是轮到的玩家，并且链表恰好包含按正确循环顺序排列的活跃玩家。 每次更新都会保留这个不变量，因此在最终牌之后，存储的牌数就是真正的最终手牌大小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = list(map(int, input().split()))
s = input().strip()

nxt = [0] * n
prv = [0] * n

for i in range(n):
    nxt[i] = (i + 1) % n
    prv[i] = (i - 1 + n) % n

cur = 0
dirv = 1

for ch in s:
    left = prv[cur]
    right = nxt[cur]

    target = right if dirv == 1 else left

    if ch == 'D':
        a[target] += 2

    a[cur] -= 1

    dead = (a[cur] == 0)

    if dead:
        l = prv[cur]
        r = nxt[cur]
        nxt[l] = r
        prv[r] = l

    if ch == 'C':
        cur = target

    elif ch == 'S' or ch == 'D':
        if dirv == 1:
            cur = nxt[target]
        else:
            cur = prv[target]

    else:  # 'R'
        dirv *= -1

        if dirv == 1:
            cur = right
        else:
            cur = left

for x in a:
    print(x)
```数组`nxt`和`prv`在活跃玩家上形成一个循环双向链表。 删除一个玩家只需要重新连接它的两个邻居，这是常数时间。 

变量`target`在任何删除之前计算。 这很重要，因为跳过和抽两指的是相对于刚刚行动的玩家的下一个玩家，而不是相对于稍后更新后的圆圈。 

对于反向卡，我们存储`left`和`right`移除之前。 如果当前玩家离开，我们仍然知道方向改变后接下来应该由哪个玩家行动。 

卡牌数量永远不会超过大约`2 × 10^5 + 2m`，它很容易适合 Python 整数。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + m) | 构建链表的时间复杂度为 O(n)，处理每张牌的时间复杂度为 O(1) |
 | 空间| O(n) | 卡片计数和链表数组 |

 该限制允许最多 200,000 名玩家和 200,000 张打出的牌。 线性模拟很容易满足时间限制，并且仅使用几个大小的数组`n`。 

## 测试用例```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    s = input().strip()

    nxt = [0] * n
    prv = [0] * n

    for i in range(n):
        nxt[i] = (i + 1) % n
        prv[i] = (i - 1 + n) % n

    cur = 0
    dirv = 1

    for ch in s:
        left = prv[cur]
        right = nxt[cur]

        target = right if dirv == 1 else left

        if ch == 'D':
            a[target] += 2

        a[cur] -= 1

        if a[cur] == 0:
            l = prv[cur]
            r = nxt[cur]
            nxt[l] = r
            prv[r] = l

        if ch == 'C':
            cur = target
        elif ch in "SD":
            cur = nxt[target] if dirv == 1 else prv[target]
        else:
            dirv *= -1
            cur = right if dirv == 1 else left

    return "\n".join(map(str, a)) + "\n"

# sample
assert run("3 6\n3 2 3\nSRDCCD\n") == "3\n0\n3\n"

# minimum style case
assert run("2 2\n1 2\nCC\n") == "0\n1\n"

# reverse with elimination
assert run("3 1\n1 5 5\nR\n") == "0\n5\n5\n"

# draw-two with elimination
assert run("3 1\n1 5 5\nD\n") == "0\n7\n5\n"

# all normal cards
assert run("4 4\n3 3 3 3\nCCCC\n") == "2\n2\n2\n2\n"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |
 |`2 2 / 1 2 / CC`|`0 1`| 最小活跃圈|
 |`3 1 / 1 5 5 / R`|`0 5 5`| 当前玩家离开时反转 |
 |`3 1 / 1 5 5 / D`|`0 7 5`| 抽两并通过淘汰跳过 |
 |`4 4 / 3 3 3 3 / CCCC`|`2 2 2 2`| 纯转旋转|

 ## 边缘情况

 考虑：```
3 1
1 5 5
S
```玩家 1 打出一张跳过牌并立即获得零张牌。 被跳过的玩家仍然是玩家 2，因为玩家 2 是打牌时的下一个活跃玩家。 该算法计算`target`在删除之前，因此会跳过正确的播放器。 最终计数变为：```
0
5
5
```现在考虑：```
3 1
1 5 5
R
```玩家 1 玩完后离开。 方向从顺时针变为逆时针。 下一个玩家必须是玩家 1 的前左邻居。该算法存储`left`和`right`在移除之前，因此即使玩家 1 消失后它也可以正确选择下一个回合。 

最后：```
3 1
1 5 5
D
```玩家 1 给玩家 2 两张牌，跳过玩家 2，然后离开。 玩家 3 成为下一个玩家。 因为该算法在移除之前应用了绘制两次效果并直接从当前位置计算跳过的玩家，所以结果准确地说：```
0
7
5
```这些情况是大多数不正确的模拟失败的地方，并且它们可以通过链表表示自然地处理。
