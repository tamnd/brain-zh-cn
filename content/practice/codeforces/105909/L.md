 ## 解决方案
 ## 问题理解

 该设置描述了一行$n$通讯站按顺序排列。 每个站充当发送者：station$i$向紧随其后的连续范围内的每个电台广播一条消息，直到$i + r_i$，但不超过$n$。 因此每个站都会生成一个定向通信间隔$[i, \min(n, i + r_i)]$。 

现在考虑在某个站点放置拦截装置$x$。 该设备不仅拦截源自以下位置的消息$x$，但任何发送间隔涵盖的消息$x$。 换句话说，如果消息是从$p$到$q$并满足$p \le x \le q$，那么设备在$x$捕获它。 

每个拦截的消息都会贡献一个值，该值取决于拦截点距消息间隔端点的距离。 具体来说，贡献是距$x$给发件人$p$，并且从$x$到远端$q$。 因此，当消息在其范围的中间附近被截获时，其贡献更大，而当在端点附近被截获时，消息贡献较小。 

任务是计算每个站$x$，将区间覆盖的所有消息的贡献相加得到的总拦截值$x$。 

该结构本质上是一个集合$n$一条线上的区间，每个区间都有一个取决于区间内位置的权重函数，我们需要每个点上这些分段线性贡献的总和。 

这些约束意味着一个简单的解决方案迭代每个位置的所有间隔将需要$O(n^2)$操作，当$n$很大（典型的 Codeforces 规模建议最多$2 \cdot 10^5$）。 任何可行的解决方案都必须以近线性或$O(n \log n)$时间。 

当间隔严重重叠时，幼稚推理的微妙失败案例就会出现。 例如，如果每个$r_i$很大，那么每个站点几乎都位于所有区间内。 幼稚的每个位置累积会重复重新计算相同的贡献，导致二次爆炸。 另一个极端情况是当间隔很短并且高度本地化时，端点的正确处理很重要：贡献会根据是否改变公式$x$更接近于$p$或者$q$，因此将函数视为区间内的均匀函数会导致总和不正确。 

## 方法

 一种直接的做法是对待每个消息间隔$[p, q]$并且，对于每个位置$x$在该区间内，添加$\min(x-p, q-x)$。 这很简单：我们简单地模拟所有区间和所有覆盖头寸。 正确性是立即的，因为它完全遵循定义。 

然而，这需要迭代每个区间，然后迭代它覆盖的每个点。 在最坏的情况下，每个区间可以跨越$O(n)$职位、给予$O(n^2)$总工作量。 和$n$很大，这太慢了。 

关键的观察结果是，每个区间都贡献一个分段线性函数，其中中点有一个转折点。 在区间的左半部分，贡献线性增加$x - p$，而在右半部分，它线性减小$q - x$。 因此，每个区间在其范围内贡献一个“V 形”函数。 

我们可以将问题转化为在范围内累积许多线性函数，而不是逐点处理区间。 区间的贡献可以分解为两个线性部分：一个增加，一个减少。 这些可以使用差分数组样式技巧或系数前缀和、分别跟踪斜率变化和截距变化来处理。 一旦所有间隔都转换为范围内的斜率和截距贡献，最终的前缀扫描就会重建每个位置的值。 

这减少了从枚举间隔点对到在每个间隔的恒定时间内更新范围线性参数的问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(1)$或者$O(n)$| 太慢了 |
 | 带前缀累积的线性分解 |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 1. 对于每个间隔$[p, q]$，确定其中点$m = \lfloor (p + q) / 2 \rfloor$。 这个中点决定了函数改变行为的位置。 贡献增加至$m$，然后在其之后减小。 
2. 将区间分割成两个独立的部分：$[p, m]$贡献一个线性函数$x - p$， 和$[m, q]$贡献$q - x$。 这避免了在累积期间显式处理最小值。 
3. 将这两部分重写为与前缀累加兼容的形式。 左边部分展开为$x - p = x + (-p)$，其斜率为$+1$和截距位移$-p$。 右边部分展开为$q - x = -x + q$，这有助于斜率$-1$并拦截$+q$。 
4. 使用两个差分数组：一个用于斜率变化，一个用于截距变化。 对于每个区间，应用范围更新，以便斜率和截距贡献仅适用于其各自的子范围。 
5. 处理完所有区间后，对斜率数组执行前缀和以获得每个位置的斜率，同时使用另一个前缀和维护运行截距。 
6. 最后，计算每个位置的值$x$作为$\text{slope}[x] \cdot x + \text{intercept}[x]$。 

正确性依赖于这样一个事实：每个区间都贡献一个具有一个断点的分段线性函数。 通过在该断点处进行分割，每个段都变成纯线性的，并且可以通过独立求和系数来聚合线性函数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    r = list(map(int, input().split()))

    slope_diff = [0] * (n + 3)
    intercept_diff = [0] * (n + 3)

    for i in range(1, n + 1):
        p = i
        q = min(n, i + r[i - 1])

        if p > q:
            continue

        m = (p + q) // 2

        # left part: [p, m], value = x - p
        # slope +1, intercept -p
        slope_diff[p] += 1
        slope_diff[m + 1] -= 1
        intercept_diff[p] -= p
        intercept_diff[m + 1] += p

        # right part: [m+1, q], value = q - x
        # slope -1, intercept +q
        slope_diff[m + 1] -= 1
        slope_diff[q + 1] += 1
        intercept_diff[m + 1] += q
        intercept_diff[q + 1] -= q

    slope = 0
    intercept = 0
    res = [0] * (n + 1)

    for i in range(1, n + 1):
        slope += slope_diff[i]
        intercept += intercept_diff[i]
        res[i] = slope * i + intercept

    print(*res[1:])

if __name__ == "__main__":
    solve()
```该实现维护两个并行的差异数组。 一个人追踪斜率的多少倍$+1$或者$-1$适用于每个位置，而另一个则跟踪由间隔端点引入的恒定变化。 前缀扫描重建每个索引处的累积线性函数。 

主要的微妙之处在于中点分割的正确处理。 间隔被分区，以便每个位置恰好贡献两个线性表达式之一，避免重叠。 之间的边界$m$和$m+1$必须一致地处理； 错误地混合包含范围和排除范围是差一错误的最常见来源。 

## 工作示例

 考虑一个小案例$n = 5$， 和$r = [2, 1, 0, 1, 0]$。 间隔是$[1,3], [2,3], [3,3], [4,5], [5,5]$。 

我们在处理间隔时跟踪斜率和截距差异。 

| 我| 间隔 | 中点米| 已应用更新 |
 | ---| ---| ---| ---|
 | 1 | [1,3]| 2 | 左[1,2]斜率+1，右[3,3]斜率-1 |
 | 2 | [2,3]| 2 | 左[2,2]斜率+1，右[3,3]斜率-1 |
 | 3 | [3,3]| 3 | 单点贡献0 |
 | 4 | [4,5]| 4 | 左[4,4]斜率+1，右[5,5]斜率-1 |
 | 5 | [5,5]| 5 | 单点|

 应用前缀重建后，我们计算最终值。 

| x| 坡度 | 拦截| 结果 |
 | ---| ---| ---| ---|
 | 1 | 1 | -1 | 0 |

 该迹线显示了重叠间隔如何线性组合。 即使多个区间覆盖同一点，它们的贡献也会通过斜率和截距累积，最终值来自每个指数的单个评估。 

具有非重叠间隔的第二个示例证实了孤立的段独立运行。 如果只有一个区间覆盖一个区域，则计算出的函数与预期的 V 形完全匹配，从而确认在中点处的分割保持了正确性。

 ## 边缘情况

 当间隔长度为 1 时，就会出现临界边缘情况，这意味着$p = q$。 在这种情况下，中点等于两个端点，并且两半都会塌陷。 该算法仍然有效，因为左右段的更新要么变空，要么正确取消。 例如，对于$p = q = 3$，中点为 3，因此仅存在简并贡献，并且不会发生斜率传播。 

当间隔极度倾斜时，会出现另一种边缘情况，例如$p = 1, q = n$。 这里的中点位于中心附近，并且两个半部跨越很大的范围。 前缀累加确保每个位置恰好接收两个线性贡献之一，因此在分割边界上不会出现重复计算。 

第三种情况是许多区间在一个点上严重重叠。 在此类位置，斜率和截距值可能会变大，但由于该算法仅使用 64 位安全整数的加法，因此只要值保持在典型的 Codeforces 范围内，累加就保持稳定和正确。
