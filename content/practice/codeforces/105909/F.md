 ## 解决方案
 ## 问题理解

 我们得到一棵带有节点值的有根树。 每个节点都带有一个整数标签，节点 1 是根。 查询选择两个节点$s$和$t$， 在哪里$t$保证是的祖先$s$，所以它们之间的路径是唯一的向上路径$s$到$t$。 

在这条向上的路径上，我们想象从以下位置开始遍历节点$s$。 一开始我们“持有”的价值$s$。 我们可以通过沿着路径选择额外的节点来扩展我们所拥有的，但只有在严格的规则下：我们可以选择一个值为$x$仅当我们已经有一个有价值的节点时$x-1$。 每个值在收集集中最多可以出现一次。 

所以沿着路径从$s$到$t$，我们正在有效地尝试提取一系列节点，其值形成一条链，如下所示$$a[s], a[s] + 1, a[s] + 2, \dots$$并且节点必须沿着树路径以向上的顺序出现。 每个查询的目标是从以下位置开始的连续价值链的最大可能长度：$s$并完全保持在路径上$t$。 

输入描述一棵树、节点上的值以及这种形式的多个查询。 每个查询都询问我们在从$s$向上但不超过上方$t$。 

从复杂性的角度来看，树的大小足够大，任何执行路径的每个查询遍历的解决方案都太慢。 单个路径可以是$O(n)$，并且可能有很多查询，因此天真的方法会降级为$O(nq)$，这是不可接受的。 我们被迫预先计算值和祖先之间的关系，以便可以在对数或接近恒定的时间内回答每个查询。 

一些边缘情况对于正确性很重要：

 一种特殊情况是根本无法进行扩展。 例如，如果路径是$s \rightarrow t$并且没有祖先$s$有价值$a[s]+1$，那么答案始终是 1。天真的贪婪扫描可能会错误地跳过节点或尝试“跳转”路径上不存在的值。 

另一个微妙的情况是当链条存在但延伸到上面时$t$。 假设完整的向上链来自$s$将继续超越$t$，但我们不被允许通过$t$。 正确的解决方案必须准确地截断链$t$，不计算其上方的节点。 

最后，相同值在不同分支中多次出现并不重要，因为只有特定路径上的祖先才是相关的。 任何忽略祖先并仅跟踪全局值邻接的解决方案都会错误地过度计数。 

## 方法

 一种直接的方法是通过从$s$直到达到$t$，将值收集到一个数组中，然后计算最长的前缀，该前缀形成从$a[s]$。 这是可行的，因为路径是明确已知的，我们可以检查每个下一个值是否按顺序存在。 

然而，每个查询可能需要遍历一段长度的路径$O(n)$。 对于许多查询，这会导致最坏情况的复杂性$O(nq)$，当两者都太慢时$n$和$q$很大。 

关键的观察是，该结构实际​​上并不是关于任意子序列，而是关于确定性的“值跳跃”。 从任意节点$u$，至多有一个有用的下一步：$u$其值为$a[u] + 1$。 如果我们有效地知道祖先，我们就可以将整个路径“压缩”成一条功能链，其中每个节点在值序列意义上最多有一个后继者。 

这将树问题变成了更接近函数图的问题：每个节点都指向根路径上连续价值链中的下一个有效节点。 一旦构建了这个指针结构，回答查询就变成了模拟我们可以沿着这些指针向上走多远，一旦超过上面就停止$t$。 

主要困难是有效地构建这些下一个指针。 这是通过在从根开始的 DFS 期间沿着当前根到节点路径按值维护节点堆栈（或堆栈映射）来解决的。 当我们到达一个节点时$u$，我们可以立即找到具有值的最近祖先$a[u]+1$，因为该值的堆栈准确地告诉我们路径上当前处于活动状态的节点。 

构建这个“下一个指针树”后，我们可以在其上预先计算二进制提升，以便每个查询都可以以对数步长跳转。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的强力路径遍历 |$O(n)$每个查询 |$O(1)$| 太慢了 |
 | DFS + 下一个指针 + 二进制提升 |$O((n + q)\log n)$|$O(n\log n)$| 已接受 |

 ## 算法演练

 我们首先构建一个结构，告诉我们每个节点其连续价值链的下一步位于何处。 

1. 从根运行 DFS，同时维护一个字典，将每个值映射到当前根到当前节点路径上的节点堆栈。 

当进入一个节点时$u$，我们将其压入对应的堆栈中$a[u]$。 这可以确保在任何时候，某个值的堆栈顶部都是该值最接近的祖先（包括其自身）。 
2.对于当前节点$u$，我们要在链中找到它的后继者，也就是最接近的有值的祖先$a[u] + 1$。 我们查看堆栈$a[u] + 1$。 如果它非空，则其顶部元素恰好是最近的此类祖先。 我们定义：$$nxt[u] = \text{top of stack}[a[u] + 1]$$如果不存在这样的堆栈，$nxt[u] = 0$。 

此步骤将“沿祖先的值邻接”压缩为每个节点的单个指针。 
3. 处理后的子项$u$，我们弹出$u$从其值堆栈中恢复其他分支的正确状态。 这使堆栈与当前 DFS 路径保持一致。 
4.一次全部$nxt[u]$指针建立后，我们将它们视为一个函数图，其中每个节点最多有一个出边。 我们建造二元升降台以便我们可以跳跃$2^k$沿着这条链条快速前进。 
5. 对于每个查询$(s, t)$，我们沿着$nxt$指针起始于$s$，但我们必须确保我们永远不会超越$t$在树上。 自从$t$是的祖先$s$，这个条件相当于要求任意访问过的节点至少有深度$\text{depth}[t]$。 

我们贪婪地采取最大可能的二元跳跃，使我们保持在有效的深度约束内，累积所采取的步数。 

### 为什么它有效

 在任意节点$u$，定义$nxt[u]$保证如果存在有效的链，它必须准确地使用下一次出现的值$a[u] + 1$。 具有相同值的任何其他祖先都会更高，并且打破了路径顺序中最接近的要求，从而防止它们之间存在有效的中间值。 

这使得链具有确定性：从$s$，就节点选择而言，恰好存在一条可能的向上最大连续值路径。 二进制提升在加速遍历的同时保留了这种确定性。 深度约束强制边界为$t$，确保我们只考虑位于查询段内的该链的前缀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, q = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    parent = [0] * (n + 1)
    depth = [0] * (n + 1)

    nxt = [0] * (n + 1)

    from collections import defaultdict
    st = defaultdict(list)

    def dfs(u, p):
        parent[u] = p
        for v in g[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            dfs(v, u)

    dfs(1, 0)

    order = []

    def build(u, p):
        order.append(u)
        st[a[u]].append(u)

        val = a[u] + 1
        if st[val]:
            nxt[u] = st[val][-1]

        for v in g[u]:
            if v == p:
                continue
            build(v, u)

        st[a[u]].pop()

    build(1, 0)

    LOG = 20
    up = [[0] * (n + 1) for _ in range(LOG)]
    for i in range(1, n + 1):
        up[0][i] = nxt[i]

    for k in range(1, LOG):
        for i in range(1, n + 1):
            up[k][i] = up[k - 1][up[k - 1][i]]

    def query(s, t):
        limit = depth[t]
        cur = s
        ans = 1

        for k in reversed(range(LOG)):
            nx = up[k][cur]
            if nx and depth[nx] >= limit:
                cur = nx
                ans += 1 << k

        return ans

    for _ in range(q):
        s, t = map(int, input().split())
        print(query(s, t))

if __name__ == "__main__":
    solve()
```该解决方案分为两个阶段。 DFS 阶段构建深度和父结构，然后第二个 DFS 构建`nxt`使用活动值堆栈的指针。 二元升降台`up[k][u]`允许沿着价值链快速跳跃。 

一个微妙的点是查询内部的深度检查。 不强制执行`depth[nx] >= depth[t]`，算法会很高兴地跳到允许的端点之上并进行计数。 另一个细节是`nxt[u]`被视为功能边，因此二进制提升是安全的，因为每个节点最多有一个传出转换。

 ## 边缘情况

 当不存在有效的扩展时，例如其值在其路径上被隔离的节点，DFS仍然分配`nxt[u] = 0`。 在查询中，二进制提升立即停止，因为没有向上转换，并且答案仍然是 1。 

当完整的连续链超出查询边界时$t$，深度条件阻止了上面跨越的跳跃$t$。 该算法仅计算深度至少为`depth[t]`，因此结果会自动截断为链的有效前缀。 

当多个节点在不同分支共享相同值时，只有当前DFS路径堆栈可见，因此`nxt[u]`始终引用正确的祖先，而不是来自另一个子树的节点。
