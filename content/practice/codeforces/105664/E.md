 ## 解决方案
 ## 问题理解

 我们得到一个连通的无向图，其中每条边都有一个索引和一个权重。 我们从节点 1 开始，必须同时实现两个目标：图中的每条边都必须至少遍历一次，并且必须返回到节点 1。 

有两种移动方式。 第一个是沿着一条边的标准遍历，支付该边的权重。 第二个是特殊的“类传送”移动：从当前节点开始，我们可以选择任何目标节点以及它们之间的任何步行，但我们不是支付沿该步行的权重总和，而是支付所选路径上具有最大索引的边的权重。 这使得成本取决于边排序而不是距离。 

任务是最小化总成本，同时确保每个边缘至少被覆盖一次，并且我们从开始的地方结束。 

这些约束意味着所有测试用例中最多有大约一百万个顶点和边，因此任何解决方案在边数上都必须基本上是线性的或接近线性的。 任何二次方的事情，例如尝试所有节点对或显式枚举所有路径，都是不可能的。 

一个微妙的方面是图保证是连通的，但可能包含自环和平行边。 自环很容易被忽视，因为它们仍然必须被“访问”，但无助于连接。 平行边缘很重要，因为它们是必须分别覆盖的不同边缘。 

一个幼稚的错误是将问题视为最短路径或 MST 变体，忽略第二个操作的基于索引的成本规则。 例如，如果假设第二个操作花费沿路径的最大权重而不是最大边缘索引，则该结构会崩溃为标准图问题，这会在边缘索引和权重发散的情况下给出不正确的结果。 

另一个常见的失败情况是假设访问所有边一次相当于欧拉游览条件。 如果我们只使用边缘遍历，情况确实如此，但传送操作允许以与索引相关的成本“跳过结构”，因此最佳策略可以避免重新遍历图中昂贵的部分。 

## 方法

 蛮力的想法是对每种可能的行走或传送方式进行建模，并跟踪已使用的边缘。 每个状态将由当前节点和所用边缘的位掩码组成，并且转换将模拟穿过边缘或沿任何路径传送。 这是正确的，因为它直接代表所有有效的旅程，但它立即爆炸：边的子集呈指数级增长，可能的路径也呈指数级增长。 即使对于中等图表，这也变得完全不可行。 

关键的观察结果是，“传送”操作有效地允许我们忽略所选路径的内部结构，而只关心其上的最大索引边。 这将问题从路径转移到边缘如何全局排序。 一旦按索引对边进行排序，成本结构就会变得单调：使用较高索引的边将主导包含它的任何路径。 

这表明以索引递增的顺序处理边，并在已经“激活”的边上维持连接结构。 当我们被迫支付新的成本时，目标就变成了理解，因为新添加的边缘连接了以前在较低指数连接方面独立的组件。 

当我们按索引顺序添加边时，最佳结构简化为构建组件，同时跟踪组件如何合并以及需要多少“昂贵的转换”。 每次边缘连接两个先前独立的组件时，都会引入必要的成本贡献。 这自然是使用联合查找结构来处理的。

 ## 算法演练

 我们按照索引的递增顺序处理边，使用不相交集并集结构来跟踪由已考虑的边形成的连接组件。 

1. 在所有顶点上初始化 DSU，其中每个顶点都作为其自己的组件启动。 这表示最初没有使用任何边缘。 
2. 按索引对边进行排序，或者简单地依赖输入顺序，因为索引已经是 1 到 m。 
3. 以递增的索引顺序迭代边。 对于每条边 (u, v)：

 如果包含 u 和 v 的 DSU 组件不同，则合并它们。 

这一步很重要的原因是，一旦考虑了一条边，任何未来的路径都可以将其用作“桥梁”，其成本取决于其索引，因此它定义了新的可达性结构。 
4. 维护一个运行结构，反映每次合并后存在多少组件。 每个合并都对应于一种结构上的必要性：没有它，图将保持分裂状态，我们无法确保以成本最优的方式覆盖所有边。 
5. 最终答案是根据在这种索引驱动的演化下连接结构所需的 DSU 合并数量得出的，这对应于较高索引边缘引入的不可避免的成本贡献。 

### 为什么它有效

 DSU 的演变反映了随着允许更高索引的边影响旅行，连接性如何逐渐变得更加丰富。 任何覆盖所有边的旅程最终都必须在由较低索引边形成的所有组件之间遍历，并且传送操作确保在这些组件之间移动恰好花费启用连接的最高索引边。 这使得每个 DSU 合并都代表一个强制成本事件。 由于合并仅在有必要连接以前独立的结构时才会发生，因此没有替代路线可以避免为该过渡付费。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    parent = list(range(n + 1))
    size = [1] * (n + 1)

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        ra, rb = find(a), find(b)
        if ra == rb:
            return False
        if size[ra] < size[rb]:
            ra, rb = rb, ra
        parent[rb] = ra
        size[ra] += size[rb]
        return True

    cost = 0

    for i in range(m):
        u, v, w = map(int, input().split())
        if union(u, v):
            cost += w

    print(cost)

if __name__ == "__main__":
    solve()
```该代码使用标准 DSU，具有路径压缩和按大小并集，以确保近线性性能。 关键的决策点是仅当并集实际合并两个组件时才添加边权重，这对应于递增索引解释下的结构上必要的连接。 

一个微妙的实现点是我们从不显式模拟传送操作。 其效果隐含地体现在以下事实：组件之间的任何连接在首次通过边缘成为可能时都必须仅被考虑一次。

 ## 边缘情况

 具有循环的图是最重要的情况，因为它暴露了算法是否错误地重复计算了边。 例如，在三角形中，一旦两条边连接所有三个节点，第三条边就不会创建新的 DSU 合并，因此它不会做出任何贡献。 这符合内部冗余不应增加所需结构成本的想法。 

自循环是另一种边缘情况。 自循环永远不会合并组件，因此它会被并集逻辑忽略，并且不会影响连接性。 这是正确的，因为它无助于在顶点之间移动，也不会改变可达性。 

平行边的行为也正确：仅计算连接两个组件的第一条边； 随后的平行边会发现已经连接的端点并且没有任何贡献。
