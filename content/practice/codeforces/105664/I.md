 ## 解决方案
 ## 问题理解

 我们有一条直线，有几个固定的着陆点，每个着陆点都位于数轴上的某个坐标处。 玩家从位置零开始，想要到达这些点中最远的点。 

移动受到限制：从当前位置开始，有两种方式可以向前移动，要么是正常跳跃，最多覆盖`x`单位，或者通过使用特殊技能来推动玩家最多前进`y`单位。 每次使用特殊技能时，它都算作一次操作，而普通跳跃是免费的，因为它们不会增加我们试图最小化的答案。 

任务是确定是否可以到达最远点，如果可以，则假设可以任意使用跳跃，则尽量减少到达那里必须使用特殊技能的次数。 

关键的隐藏结构是，任何时刻只有最大可到达位置才是重要的。 中间着陆点是存在的，但它们仅在允许向更大坐标前进的情况下才重要。 

这些限制意味着据点的数量最多为几千个，而坐标最多为一百万个。 这立即表明排序和扫描就足够了，任何尝试模拟点之间移动的所有组合的方法仍然可以，只要它大致是二次或更好的。 任何立方或更差的东西都可能成为边界，但由于小而仍然可能通过`n`。 

一个常常失败的天真的想法是独立对待每个立足点，从一开始就决定它是否可以通过一步或两步到达。 这忽略了一个事实，即到达远处可能需要链接多个中间立足点，其中特殊技能的最佳使用取决于早期的选择。 

当出现第二个微妙的陷阱时`x`和`y`非常不同。 如果`x`大于或等于`y`，特殊技能其实没什么用，但是如果`y`较大，那么如果过度使用它会强制跳过有用的中间点，那么过度使用它可能是有害的。 该结构在位置上是单调的，但在成本上却不是单调的。 

## 方法

 暴力方法将模拟立足点之间所有可能的移动顺序。 从每个位置，我们可以尝试使用任一移动类型跳转到任何可到达的下一个点，并跟踪技能使用的次数。 这自然成为完整有向图上的最短路径问题，其中边表示通过任一跳跃类型的可达性。 

虽然正确，但这种方法成本太高，因为每个`n`我们可能会考虑过渡到所有后面的点，从而导致大约`O(n^2)`边，运行完整的最短路径将需要额外的开销。 这已经面临边缘化的风险，任何更明确的国家扩张都变得不可行。 

关键的观察是，我们实际上不需要以复杂的方式跟踪“我们来自哪个立足点”。 重要的是我们是否能够以给定的技能使用次数到达某个点，同时始终保持贪婪意义上最远的可到达位置。 这将问题变成了一个一维级数问题，我们以递增的顺序处理点，并通过给定数量的特殊动作保持最佳的可实现范围。 

我们不是在所有转变上进行分支，而是保持动态状态：对于每个立足点索引，我们计算达到它所需的特殊技能的最小数量。 对于过渡，我们只关心是否可以使用自由跳跃和昂贵技能的某种组合来弥补两点之间的差距。 这将每次转换减少为简单的算术检查。

 ## 算法演练

 首先，将所有立足点按升序排列。 目标是始终推理从左向右移动，因为向后移动永远无法帮助到达最远点。 

我们定义一个动态值`dp[i]`作为达到该目标所需的特殊技能使用的最少数量`i`第-个立足点。 

我们初始化`dp[0] = 0`，因为我们从位置零开始，没有使用技能。 

为了每一个立足点`i`，我们尝试更新所有可到达的立足点`j > i`。 

对于每对`(i, j)`，计算距离`d = a[j] - a[i]`。 

然后我们确定最多有多少步大小`x`我们可以不使用特殊技能来获取。 让`base = x`。 如果`d <= base`，我们可以从`i`到`j`不使用特殊技能，所以我们设置`dp[j] = min(dp[j], dp[i])`。 

否则，我们计算有多少个完整的`x`-我们可以使用的跳跃以及耗尽它们后剩下的内容。 剩余的缺口使用特殊技能来处理，并且每次使用都会贡献一个单位的成本。 我们更新`dp[j] = min(dp[j], dp[i] + ceil((d - x) / y))`。 

最终的答案是`dp[n-1]`如果是有限的，否则目的地无法到达。 

正确性依赖于这样一个事实：两个立足点之间的任何最佳路径都可以分解为片段，在这些片段中我们可以使用自由跳跃前进到极限`x`，然后才使用特殊动作来弥补剩余的距离。 由于仓位是线性且严格递增的，因此重新审视之前的点无助于降低成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, x, y = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    INF = 10**18
    dp = [INF] * n
    dp[0] = 0

    for i in range(n):
        for j in range(i + 1, n):
            d = a[j] - a[i]
            if d <= x:
                dp[j] = min(dp[j], dp[i])
            else:
                rem = d - x
                need = (rem + y - 1) // y
                dp[j] = min(dp[j], dp[i] + need)

    ans = dp[n - 1]
    print(ans if ans < INF else -1)

if __name__ == "__main__":
    solve()
```代码首先对立足点进行排序，以便转换始终向前移动。 DP 数组存储每个位置的最小技能使用情况。 双循环考虑了每一个可能的向前跳跃。 

微妙的部分是处理单个正常跳跃不能覆盖间隙的情况。 我们没有尝试显式地模拟多次交替跳跃，而是将效果压缩为简单的算术计算：在一次最大正常跳跃大小之后`x`，剩余的距离通过重复使用特殊技能来覆盖，每次贡献`y`进步。 

最终检查确保无法到达的状态仍标记为无限。

 ## 边缘情况

 一种边缘情况是所有立足点都非常接近，在一定距离内`x`。 在这种情况下，根本不需要使用任何技能。 该算法处理这个问题是因为每个转换都满足`d ≤ x`， 所以`dp[n-1]`始终保持为零。 

另一个边缘情况是当`x = 0`。 那么正常的移动就不可能了，每一次的转变都必须完全依靠特殊的技巧。 该公式彻底退化为重复除以`y`，并且 DP 仍然正确地累积所需的使用量。 

第三种情况是当`y = 0`，意味着特殊技能根本无法移动。 在这种情况下，只有间隙`≤ x`是可穿越的。 任何较大的间隙都会导致 DP 值无穷大，最终答案将变得无法达到，算法正确地将其输出为`-1`。
