 ## 解决方案
 ## 问题理解

 我们得到一个数字序列和一个初始值$x$。 我们可以任意重新排序序列。 固定顺序后，我们从左到右处理元素，重复替换当前值$x$与除以下一个数组元素时的余数。 

每次操作只能减少当前值或保持不变，因为$x \bmod a_i$始终在范围内$[0, a_i - 1]$。 目标是选择数组的顺序，使最终值$x$所有操作后尽可能大。 

关键对象不是最终序列本身，而是每个模运算如何限制该时刻的值。 过早放置的大元素可能会立即破坏信息，而过早放置的小元素可以通过勉强减少信息来保留较大的价值。 

限制条件非常严格$n$， 和$n \le 21$。 这立即表明允许对子集或排列进行指数策略。 然而，值本身可以大到$10^{18}$，因此任何依赖于枚举简单转换之外的数字状态的方法都是不可能的。 这促使我们采用一种仅跟踪过程的结构信息而不是精确的算术探索的状态定义。 

天真的解释可能会尝试数组的所有排列并模拟该过程。 这在逻辑上可行，但在计算上失败，因为$n!$即使在$n = 21$。 

第二个天真的想法是对子集进行动态编程，我们准确地存储当前值。 这也会失败，因为值范围可达$10^{18}$，并且同一子集可以根据顺序产生许多不同的中间值。 

当大量数字以不明显的顺序相互作用时，就会出现打破贪婪直觉的边缘情况。 例如，如果$x = 100$数组是$[60, 50, 40]$，将 60 个第一产量$100 \bmod 60 = 40$，但先放置 40 给出$100 \bmod 40 = 20$，以后情况会更糟。 局部最优选择在后续步骤中不稳定，因此按值进行贪婪排序是不可靠的。 

## 方法

 暴力方法是尝试数组的每个排列，模拟求模过程，并取最大结果。 每次模拟费用$O(n)$，并且有$n!$排列，因此总工作量增长为$O(n! \cdot n)$。 即使在$n = 15$，这变得不可行。 

关键的观察结果是，顺序仅通过在每个步骤中应用哪个元素而起作用，并且状态空间由所使用的元素的子集控制。 自从$n \le 21$，我们负担得起$2^n$状态，我们可以定义子集上的动态规划。 

关键的见解是，该过程在 DP 意义上是可逆的：我们可以考虑选择下一个元素以在序列中最后应用，而不是向前构建序列。 如果我们知道应用元素子集后的结果，我们可以尝试在末尾添加一个元素并计算结果值。 这将创建一个子集 DP，其中每个状态对应于一组使用的元素以及按某种顺序处理它们后的结果值。 

我们通过掩码定义 DP，但通常每个掩码只存储一个值是不够的，因为同一子集的不同阶数可能会产生不同的结果。 诀窍在于，我们不需要所有值，只需要每个子集的最佳可实现值，因为我们正在最大化最终结果。 

这导致了标准的“具有值转换的子集 DP”，其中每个状态尝试扩展一个未使用的元素并应用模转换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力（所有排列）|$O(n! \cdot n)$|$O(n)$| 太慢了 |
 | 掩码上的 DP 子集 |$O(n \cdot 2^n)$|$O(2^n)$| 已接受 |

 ## 算法演练

 1. 我们定义一个位掩码，表示哪些元素已在流程中使用，以及当前值$x$按某种顺序应用这些元素之后。 每个掩码代表一个集合，而不是一个序列，因此 DP 仅保留该集合的最佳可实现结果。 
2.我们用一个空集初始化DP，其中的值是原始的$x$。 这对应于尚未应用任何模运算。 
3. 对于每个元素子集，我们尝试将一个未使用的元素添加到序列中。 如果当前状态是$(mask, value)$我们尝试元素$a_i$，新值变为$value \bmod a_i$，新的掩码包括$i$。 
4. 我们通过取当前值和新计算值之间的最大值来更新新掩码的 DP 条目。 这确保了如果多个订单导致相同的子集，我们只保留最佳结果。 
5. 处理完所有子集后，答案是所有完整掩码中的最大值，因为任何排序都对应于最终使用所有元素的路径。 

### 为什么它有效

 DP 保持了这样的不变性：对于元素的每个子集，它存储 的最大值$x$在按某种顺序应用这些元素后可以实现。 任何完整排列都对应于通过子集的路径，其中每一步仅添加一个元素。 由于每个转换都保留了模运算的正确性，并且我们考虑了每个子集所有可能的最后步骤，因此不会错过任何有效的排序，并且整个子集上的最大值必须是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
x = int(input())

N = 1 << n
dp = [-1] * N
dp[0] = x

for mask in range(N):
    cur = dp[mask]
    if cur == -1:
        continue
    for i in range(n):
        if not (mask >> i) & 1:
            nxt = cur % a[i]
            nmask = mask | (1 << i)
            if nxt > dp[nmask]:
                dp[nmask] = nxt

ans = max(dp)
print(ans)
```DP 数组存储所用元素的每个子集的最佳可实现值。 转换循环遍历所有未使用的元素并应用模运算。 掩码迭代的顺序并不重要，因为所有转换仅依赖于较小或相等的子集，并且始终改进或维持存储的值。 

一个微妙的点是，覆盖状态是安全的，因为我们只关心最大化最终值，而不是重建确切的序列。 另外，初始化未使用的状态$-1$防止无效转换的传播。

此跟踪显示不同的偏序如何导致不同的中间值，并且 DP 保留每个子集的最佳值。

 ## 边缘情况

 单元素数组是最简单的场景。 该算法用以下方式初始化 DP$x$，并立即应用唯一的元素给出$x \bmod a_0$，这正确地反映在包含该元素的最终掩码中。 

其中一个值为 1 的情况是极端的，因为任何以 1 为模的操作都会将该值压缩为零。 DP 自然会避免过早应用 1，除非受到完全覆盖的强制，因为它始终保持每个子集的最大值。 

数量非常大的情况，例如$10^{18}$在 Python 中不会导致溢出问题，但在具有固定宽度整数的语言中，必须注意确保在乘法或其他运算之前应用模数。 这里，仅使用模，因此值保持安全的界限。 

当小数字与大数字并排出现时，就会出现微妙的排序陷阱。 DP 正确地探索两个顺序，确保尽可能避免早期崩溃，并通过子集探索发现最佳序列。
