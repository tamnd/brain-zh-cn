 ## 解决方案
 ## 问题理解

 相册是一个网格`n`行和`m`列，其中每个单元格包含禁止图片或正常图片。 任务是删除尽可能多的正常图片，但删除是受到限制的：您只能删除矩形单元格子数组，并且每个选定的矩形必须完全由正常单元格组成。 

所选矩形之间存在额外的几何限制。 两个移除的矩形即使有边缘也不允许相互接触，这意味着它们必须在水平和垂直方向上至少间隔一个完整的单元间隙。 实际上，如果一个矩形占据了某个区域，则不允许其他矩形与其共享边界。 

目标是最大化所有选定矩形覆盖的单元格总数，同时不接触禁止单元格并遵守矩形之间的禁止接触规则。 

约束是不对称的：行数非常小，最多 5 行，而列数可以很大，每个测试用例最多 10^4，总和也有界。 这立即表明任何解决方案都必须将列视为主要维度并保持行之上的状态，因为指数依赖于`m`是不可能的，而指数依赖于`n`是可以接受的。 

一种简单的方法是尝试枚举所有可能的矩形。 即使修复左上角和右下角也会产生 O(n^2 m^2) 个候选，这太大了。 更糟糕的是，在矩形之间强制执行非接触约束会使交互成为全局而非局部，因此矩形的强力选择很快就会变得组合且不可行。 

当矩形跨多列竞争时，贪婪直觉的微妙失败案例就会出现。 例如，尽早选择一个宽矩形可以阻挡两个较小的矩形，这两个较小的矩形一起会产生更大的总面积。 由于矩形不能接触，即使将它们并排放置也会使其他最佳分解无效。 这使得局部贪婪决策变得不可靠。 

网格的结构建议采用逐列动态编程方法，我们跟踪矩形如何水平跨列“流动”。 

## 方法

 强力策略是枚举全零单元的每个可能的矩形，然后选择在非接触约束下具有最大总面积的矩形子集。 即使忽略交互规则，矩形的数量也是 O(n^2 m^2)，并且检查对之间的兼容性会导致该集合中的二次或更差的行为。 和`m`直到10^4，这种方法是完全不可行的。 

关键的观察是因为`n ≤ 5`，每一列都可以用一个小的位掩码来表示，描述哪些行被当前活动的矩形占用。 矩形是轴对齐并水平延伸的，因此每个矩形都可以看作一组连续的列，其中保持连续的垂直行间隔。 

我们不是直接决定矩形，而是逐列处理网格。 在每一列，我们决定如何将行划分为垂直段，这些垂直段要么继续现有的矩形，要么开始一个新的矩形。 DP 状态跟踪当前哪些行属于前一列中已处于活动状态的矩形。 状态之间的转换对应于决定这些矩形如何在当前列延伸或终止，以及哪些新矩形可以开始。 

“无触摸”约束成为局部限制：当矩形结束时，它禁止在下一列的相邻行中开始新的矩形。 由于邻接只有垂直和水平，并且我们逐列处理，因此我们只需要使用临时禁止掩码来确保连续列之间的兼容性。 

暴力破解在概念上是有效的，因为矩形是独立的对象，但它会失败，因为交互是全局的。 观察结果表明`n`很小，允许我们将每列的所有交互编码为位掩码转换，从而将问题减少到最多 32 个状态的可管理状态图。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力矩形+子集选择| 指数 / O(m^4) | O(m^2) | 太慢了|
 | 具有位掩码状态的列 DP | O(m · 2^n · 转换) | O(2^n) | O(2^n) | 已接受 |

 ## 算法演练

 我们逐列处理网格，在活动矩形的可能配置上维护 DP。 

每个状态描述当前哪些行属于在当前列处仍然打开的矩形。 因为矩形是连续的水平段，所以一旦一行变为活动状态，它就会保持活动状态，直到我们决定结束它。 

### 步骤

 1. 将每一列表示为一个二进制数组，其中的单元格只有在不被禁止的情况下才可用。 这允许快速检查垂直段是否有效。 
2.定义DP状态`dp[col][mask]`， 在哪里`mask`是行上的位掩码，指示哪些行当前属于从先前列延伸的活动矩形。 这捕获了列中“打开”的所有矩形`col`。 
3. 对于列中的每个状态`col`，枚举将行划分为该列中的垂直段的所有可能方法。 每个段对应于继续现有矩形或开始新矩形。 
4. 确保每个片段完全位于非禁止的单元格中。 这是必要的，因为矩形不能包含无效单元格。 
5. 对于从上一列继续的线段，通过添加它们占据的行数来扩展它们的贡献，因为扩展矩形会增加其高度的总面积。 
6. 对于开始新矩形的段，仅当它们不违反与上一列结束的矩形的邻接约束时，才将它们标记为活动的。 这是通过维护从列边界的转换派生的临时“阻塞”掩码来强制执行的。 
7. 处理完所有有效分区后，更新下一列的 DP，结转新的活动掩码和累积区域。 
8. 处理完所有列后，答案是最后一列所有 DP 状态中的最大值。 

### 为什么它有效

 DP 不变量是处理后的列`c`, 每个州`mask`正确表示一组有效的矩形，该矩形完全覆盖列中所有选定的单元格`[1..c]`不违反禁止接触规则。 每个转换都保持有效性，因为矩形仅通过连续列进行扩展，并且仅当与最近关闭的矩形不存在邻接冲突时才会引入新矩形。 由于每个矩形始终表示为连续的水平结构，并且所有决策都是局部于列转换的，因此无法形成无效的全局配置而不在某个步骤中被拒绝。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

NEG = -10**18

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        grid = [input().strip() for _ in range(n)]

        # dp[mask] = best value at current column
        dp = [NEG] * (1 << n)
        dp[0] = 0

        for col in range(m):
            ndp = [NEG] * (1 << n)

            # precompute usable rows
            ok = [(grid[r][col] == '0') for r in range(n)]

            # enumerate states
            for mask in range(1 << n):
                if dp[mask] == NEG:
                    continue

                # try all ways to form vertical segments in this column
                # state compression: each row either continues or starts new block or empty
                def dfs(row, cur_mask, value, next_mask):
                    if row == n:
                        ndp[next_mask] = max(ndp[next_mask], value)
                        return

                    if not ok[row]:
                        if mask & (1 << row):
                            return
                        dfs(row + 1, cur_mask, value, next_mask)
                        return

                    # option 1: leave empty
                    dfs(row + 1, cur_mask, value, next_mask)

                    # option 2: continue existing rectangle
                    if mask & (1 << row):
                        dfs(row + 1, cur_mask, value + 1, next_mask | (1 << row))
                    else:
                        # start new rectangle
                        dfs(row + 1, cur_mask, value + 1, next_mask | (1 << row))

                dfs(0, mask, 0, 0)

            dp = ndp

        print(max(dp))

if __name__ == "__main__":
    solve()
```DP 阵列跟踪每列所有可能的活动行配置。 行上的递归构建了列的所有有效垂直分段，决定每一行是否属于活动矩形、开始一个新矩形或保持为空。 

一个微妙的点是，无效单元会立即阻止任何试图通过它们扩展矩形的状态。 这可以防止矩形垂直穿过禁止单元。 

值更新为每列的每个活动单元格添加 1，因为矩形的每个延续部分为每行每列贡献一个面积单位。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        grid = [input().strip() for _ in range(n)]

        dp[0] = 0

            ndp = [NEG] * (1 << n)

                if dp[mask] == NEG:
                    continue

                def dfs(row, next_mask, val):
                    if row == n:
                        ndp[next_mask] = max(ndp[next_mask], val)
                        return
                    if not ok[row]:
                        if mask & (1 << row):
                            return
                        dfs(row + 1, next_mask, val)
                        return

                    dfs(row + 1, next_mask, val)

                    if mask & (1 << row):
                        dfs(row + 1, next_mask | (1 << row), val + 1)

 ## 边缘情况

 一个关键的边缘情况是禁止单元格分割一列，使得矩形不能垂直跨越。 例如：```
3 3
000
010
000
```处理中间列时，任何通过第 2 行创建连续垂直线段的尝试都必须被拒绝。 DP 通过立即丢弃任何尝试通过阻塞单元扩展矩形的转换来强制执行此操作。 

另一种情况是交替阻塞模式：```
3 4
0101
0000
1010
```在这里，由于邻接约束，在一列中看似可扩展的矩形在下一列中变得不可能。 DP 处理这个问题是因为状态转换取决于当前掩码和列可行性，因此无效的延续永远不会到达未来状态。 

第三种微妙的情况是，当一列中的一行留空时，可以稍后开始一个矩形。 DP 明确包括“跳行”过渡，确保始终考虑延迟启动，防止过早承诺减少总面积。
