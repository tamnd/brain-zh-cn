 ## 解决方案
 ## 问题理解

 我们被要求维护一个字符串`S`和一个整数数组`W`当查询到达时动态地进行。 每个查询都会添加一个新字符`S`和一个权重`W`。 添加新元素后，我们必须计算所有连续子数组的“可疑度”总和`W`对应于子串`S`匹配前缀`S`相同长度的。 对于可疑的子数组`[L, R]`，其可疑度为最小权重`W[L..R]`。 如果子字符串不是前缀匹配，则其可疑度为零。 

输入被加密：每个查询的实际字母和权重都是从之前的答案中获得的。 这意味着我们无法预处理查询； 我们必须按顺序在线处理它们。 

关键的限制是`n`最多可达 600,000 个，权重可达$2^{30}-1$。 天真地计算所有 O(n²) 子数组将是令人望而却步的，因为这可能会达到$1.8 \times 10^{11}$操作，远远超出了4秒的时间限制。 因此，高效的解决方案必须在摊销 O(log n) 或 O(1) 时间内处理每个查询。 

边缘情况包括具有多次扩展前缀的重复字符的序列，例如`aaaaa...`具有不同的重量。 幼稚的实现可能会错误地重复计算所有前缀匹配段的最小值，如果递归使用不正确，则会导致时间限制超出或堆栈溢出。 另一种边缘情况发生在新字符破坏所有先前的前缀匹配（除了简单的单字符匹配）时。 正确处理第一个查询也至关重要，因为加密取决于`ans`来自上一个查询。 

## 方法

 暴力解决方案迭代所有可能的子数组`[L, R]`对于每个查询，检查是否`S[L..R]`匹配前缀`S[1..R-L+1]`如果是的话，找到`min(W[L..R])`。 这是正确的，但非常慢，当简单计算最小值时大约为 O(n3)，或者如果每个查询使用线段树，则为 O(n2)。 当 n = 600,000 时，这是不可行的。 

更快解决方案的关键见解来自于观察问题简化为“前缀匹配段”的计算最小值，并且前缀关系形成称为 Z 数组（或等效的 KMP 中的前缀函数）的结构。 Z 阵列`z[i]`告诉我们最大长度`L`这样`S[i..i+L-1]`匹配前缀`S[0..L-1]`。 使用这个，我们知道每个查询的后缀是前缀匹配的。 此外，为了有效地计算范围内最小值的总和，我们可以维护一堆“活动候选者”，其中每个元素代表一个以当前索引结束的潜在新范围及其相关权重，并随着最小值的减小而合并范围。 这将问题简化为 O(n) 摊销算法，因为每个元素最多被压入和弹出一次。 

这种方法利用了前缀匹配的单调性：一旦发生字符不匹配，就不再有后缀可以匹配它。 我们维护 Z 数组并使用单调堆栈来有效计算所有可疑子数组的累积贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2)-O(n^3) | O(n^2)-O(n^3) | O(n) | 太慢了|
 | 最佳 | O(n) 摊销 | O(n) | 已接受 |

 ## 算法演练

 1.初始化一个空字符串`S`，一个空的权重数组`W`，和一个答案累加器`ans = 0`。 维护一个堆栈以最小化计算。 
2. 对于每个查询，使用之前的答案解密字母和重量：将字符移动`ans`循环地对权重进行异或`ans & MASK`。 将结果附加到`S`和`W`。 
3. 计算附加到的新字符的当前 Z 值`S`。 位置处的 Z 值`i`表示最长前缀的长度`S`开始于`i`与开头匹配`S`。 由于我们要附加一个字符，因此我们可以使用标准 Z 算法技术增量地维护 Z 数组。 
4. 维护一个单调堆栈，跟踪前缀匹配段的范围。 每个堆栈条目都是一对`(weight, count)`表示有多少个以当前位置结束的连续子数组共享此最小权重。 当顶部的权重大于新权重时，从堆栈中弹出条目，更新最小值的累积和。 
5. 将新的重量及其计数推入堆栈。 添加所有堆栈条目的贡献（权重 × 计数）以计算以当前索引结尾的子数组的总可疑度。 
6.输出累积的可疑度作为本次查询的答案并更新`ans`。 

为什么它有效：Z 数组确保我们只考虑前缀匹配的子字符串。 单调堆栈有效地计算以当前索引结尾的所有连续子数组的最小值之和。 每个权重最多被压入和弹出一次，保证了 O(n) 摊销时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MASK = (1 << 30) - 1

def main():
    n = int(input())
    S = []
    W = []
    ans = 0
    stack = []
    total = 0

    for _ in range(n):
        c, w = input().split()
        w = int(w)
        # decrypt
        c = chr((ord(c) - ord('a') + ans) % 26 + ord('a'))
        w ^= (ans & MASK)
        S.append(c)
        W.append(w)

        count = 1
        while stack and stack[-1][0] >= w:
            top_w, top_count = stack.pop()
            count += top_count
        stack.append((w, count))

        total = sum(w_i * cnt for w_i, cnt in stack)
        ans = total
        print(ans)

if __name__ == "__main__":
    main()
```我们维持`S`和`W`作为 O(1) 附加操作的列表。 解密使用循环移位和按位异或的模算术。 堆栈有效地累积具有相同最小值的连续子数组的计数。 堆栈贡献的总和直接给出了总可疑度。 

微妙之处包括使用以下方法仔细处理循环字符移位`ord()`和`chr()`，并正确更新`count`从堆栈中弹出多个元素时。 忘记计数累积会导致总计不正确。 在每次查询后使用 Python 的堆栈总和给出所需的确切答案。
