 ## 解决方案
 ## 问题理解

 我们得到一棵有根树，其中每个节点都有一个隐藏的整数值。 我们所知道的是树结构，以及每个节点的一个数字`c_i`。 这个数字告诉我们子树的局部信息：在子树内的所有节点中`i`， 确切地`c_i`其中的值严格小于`i`。 

任务是重建与所有这些子树约束一致的整数对节点的任何分配。 如果多个作业有效，则任何一个作业都是可以接受的，如果没有一个作业可以满足所有约束，我们必须报告不可能性。 

关键的困难在于，每个节点都会施加一个取决于其子树内部比较的约束，但这些比较取决于我们事先不知道的值的全局排序。 树将这些约束耦合到不同的级别，因此对节点的简单独立处理会失败。 

限制允许最多 2000 个节点。 这个值足够小，以至于具有三次或二次因子的解决方案可以通过，但是任何尝试显式推理所有值​​分配或模拟值排列的任何操作都是不可行的。 我们应该期待的是一个建设性的过程，在保持一致性的同时逐步分配值。 

当人们试图在不考虑子树结构的情况下贪婪地赋值时，就会出现一种常见的失败模式。 例如，按 BFS 顺序或按父级在子级之前分配值会忽略这一点`c_i`取决于完整的子树，而不仅仅是直接邻居。 如果我们尝试仅根据对节点进行排序来分配值，则会出现另一个微妙的失败`c_i`， 因为`c_i`不代表全局排名，仅代表子树相对排名。 

一个小的说明性问题：考虑一位父母`c = 0`和一个孩子`c = 1`。 如果我们贪婪地赋值，使得更小的`c`意味着较小的值，我们可能会在子树内部强制产生矛盾，因为父约束取决于两个孩子同时排序，而不是单独排序。 

## 方法

 一个蛮力的想法是尝试从排列中分配值`1..n`到节点并检查所有约束是否成立。 对于每个分配，验证条件需要计算子树计数，这本身需要每个节点的 DFS 或合并遍历。 即使检查一项作业需要`O(n^2)`，尝试所有排列是`O(n!)`，这远远超出了任何限制。 

问题的结构表明我们需要以尊重局部子树约束的方式构造值，同时逐渐固定相对顺序。 关键的观察是`c_i`描述子树中有多少个节点必须放置在节点之前`i`按值排序，但仅相对于该子树内仍然“可用”的节点。 

这引出了一个建设性的想法：从叶子向上处理树，并在每个节点决定其子树中节点之间的相对排名。 如果我们已经知道子树的顺序，我们可以合并它们并将父树插入到与以下内容一致的位置`c_i`。 由于子树是不相交的，因此合并的行为就像合并排序列表，并且约束减少为选择正确的插入点。 

我们为每个节点维护一个位置列表，表示有多少元素小于每个候选位置。 当组合子节点时，我们合并这些列表，然后将当前节点放置在恰好`c_i`其子树中的元素较小。 

这将问题简化为树DP，其中每个节点在其子树中构建可能等级的排序结构。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力排列检查 | O(n!·n^2) | O(n!·n^2) | O(n) | 太慢了|
 | 具有有序合并的树DP | O(n^2) | O(n^2) | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 1. 在节点处建立树根`p_i = 0`。 我们将计算每个子树内的有效相对顺序。 
2. 对于每个节点，定义一个列表，表示其子树中节点的最终排序。 我们不存储实际值，而是按概念排序顺序存储位置。 
3. 从根执行DFS。 对于叶节点，其列表仅包含其自身，因为没有要违反的内部约束。 这是基本情况。 
4. 对于内部节点，首先递归计算所有子节点的列表。 每个子节点已经代表其子树的一致顺序。 
5. 将所有子列表合并为一个列表。 这种合并是通过连接然后将结果视为单个多组位置来完成的。 在这个阶段，我们只关心子树内部的相对大小。 
6. 合并子节点后，我们必须将当前节点插入到这个合并列表中，以便准确地`c_i`其子树中的元素都小于它。 这意味着将其放在索引处`c_i`合并列表的从零开始的排序。 
7.如果`c_i`大于合并列表的大小，则无法放置并且构造立即失败。 
8. 完整的 DFS 完成后，我们就得到了从最小值到最大值的有效节点排序。 分配递增的整数`1..n`按照这个顺序。 

### 为什么它有效

 每个子树在组合之前都会被独立处理，因此每个子树列表都正确地表示有效的内部排序。 当我们在位置插入一个节点时`c_i`，我们严格执行其子树中较小元素的数量。 由于子子树是不相交的，因此合并不会破坏先前满足的约束。 DFS 不变量是每个子树列表都可以向上扩展而不违反任何`c_i`，因此最终的根结构编码了全局一致的排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
children = [[] for _ in range(n)]
c = [0] * n
root = -1

for i in range(n):
    p, ci = map(int, input().split())
    c[i] = ci
    if p == 0:
        root = i
    else:
        children[p - 1].append(i)

# Each node returns a list of nodes in increasing order of final value
def dfs(u):
    cur = [u]
    for v in children[u]:
        sub = dfs(v)
        cur.extend(sub)

    # We need to place u so that exactly c[u] elements in its subtree are smaller
    # but cur currently includes u at front; we will reposition it.
    cur.remove(u)

    if c[u] > len(cur):
        raise ValueError("impossible")

    cur.insert(c[u], u)
    return cur

try:
    order = dfs(root)
    ans = [0] * n
    for i, node in enumerate(order):
        ans[node] = i + 1

    print("YES")
    print(*ans)
except ValueError:
    print("NO")
```其实现实际上遵循 DFS 构造。 每个递归调用都会构建子树的排序。 我们暂时包含节点本身，然后将其删除并重新插入到由`c_i`。 这避免了复杂的计数逻辑，因为插入位置直接强制该子树排序中存在多少个较小的元素。 

最后的赋值步骤将构造的全局顺序映射到值`1..n`，这始终有效，因为只有相对顺序才重要。 

一个微妙的实现点是递归深度，因为树可以退化为链。 增加递归限制可防止 Python 中的堆栈溢出。

 | 测量 | 复杂性 | 说明|

 | 时间 | O(n^2) | O(n^2) | 每个 DFS 合并都涉及子树大小的列表操作，并且每个节点可以插入到大小最多为 n | 的列表中。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    children = [[] for _ in range(n)]
    c = [0] * n
    root = -1

    for i in range(n):
        p, ci = map(int, input().split())
        c[i] = ci
        if p == 0:
            root = i
        else:

    sys.setrecursionlimit(10**7)

        cur = [u]

        ans = [0] * n

            ans[v] = i + 1
        return "YES\n" + " ".join(map(str, ans))
    except:
        return "NO"

 ## 边缘情况

 单节点树始终有效，因为`c_1`必须为零，并且唯一有效的分配是微不足道的。 DFS 返回一个单例列表，并且在位置零处插入可以保持正确性。 

一个节点与`c_i`大于其子树大小立即使构造变得不可能。 在该算法中，这是在插入时检测到的`c_i > len(cur)`在放置之前，确保尽早拒绝，而不是产生格式错误的订单。 

星形树强调合并许多独立的子子树。 由于每个子项都贡献不相交的排序，因此串联保留了有效性，并且根插入位置控制最终结构而不会产生歧义。
