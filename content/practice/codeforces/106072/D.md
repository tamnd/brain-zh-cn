 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，其中每个值代表生物的初始攻击力。 从这个数组中，我们可以选择任何非空子序列，这意味着我们可以选择索引的任何子集，同时保持其原始顺序。 

一旦选择了子序列，我们就在其上模拟一个过程。 我们反复挑选一个剩余的元素，“出售”它，当我们这样做时，所选子序列中的所有其他尚未售出的元素都会增加出售的价值。 这一过程一直持续到只剩下一个元素为止。 子序列的值被定义为如果我们最优地选择卖出订单，最后剩余元素的最大可能的最终攻击值。 

任务是为原始数组的每个可能的非空子序列计算该值，并对所有这些子序列求和以 998244353 为模。 

约束非常大：测试用例的总长度最多为 2 × 10^5。 任何尝试显式枚举子序列或模拟流程的解决方案都将立即失败。 即使每个测试用例的 O(n^2) 也已经太大了，因为子序列的数量呈指数级增长。 

幼稚的实现会以多种方式失败。 首先，即使枚举所有子序列也不可能超过 n 大约 40。其次，即使我们将自己限制为单个子序列，模拟最优销售订单也需要推理所有排列，而排列的大小是阶乘的。 例如，对于[1,2,3]，不同的顺序会产生不同的最终结果，并且只有仔细选择的顺序才能达到最大值。 将其扩展到所有子序列会使复杂性乘以 2^n，这是不可行的。 

当值等于或为零时，会出现微妙的边缘情况。 例如，如果所有 Ai 都为零，则无论操作如何，每个子序列的值都为零，但天真的“贪婪最大选择”模拟可能仍会尝试错误地累积变化并过度计算中间状态。 

另一个重要的极端情况是大小为 1 或 2 的小子序列。对于单个元素 [x]，答案显然是 x。 对于两个元素 [a, b]，最佳策略总是导致最终值 a + b，因为无论哪个先卖出，另一个都会恰好增加一次。 

## 方法

 我们从暴力的角度开始。 对于每个子序列，我们将模拟所有可能的销售订单并计算最佳的最终值。 即使固定长度为 k 的子序列，也有 k 个！ 订单，每次模拟都是 O(k)，所以每个子序列已经变成 O(k · k!)。 由于有 2^n 个子序列，这种方法完全爆炸。 

即使我们尝试简化模拟，我们仍然面临关键的困难：该过程是顺序相关的，并且对固定子序列的朴素贪婪推理在全局范围内并不是立即显而易见的。 

关键的观察是扭转视角。 我们考虑的不是“出售业务增加其他业务”，而是考虑贡献：每个元素最终都会根据顺序多次添加到最终幸存者中，并且最佳流程确保贡献是结构化的而不是任意的。 

关键的结构见解是，在固定子序列的任何最佳过程中，我们可以将一个元素视为最终的幸存者，而所有其他元素都以某种顺序有效地“删除”，以最大化它们对其的贡献。 这将这个过程变成了组合累积问题而不是动态模拟问题。 

一旦我们以这种方式重新解释该过程，子序列的值仅取决于所有元素的聚合贡献，并且子序列的组合变得可以跨元素分离。 每个元素独立地对许多子序列做出贡献，具体取决于包含它的子集数量以及它如何充当最终幸存者。

这将问题转化为计算每个元素作为最终主要贡献者参与的子序列数量，并根据它可以被其他选定元素包围的方式进行加权。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n · n!) | O(2^n · n!) | O(n) | 太慢了 |
 | 最佳 | O(n) 或 O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们以一种使贡献呈线性的方式重新解释子序列的最终值。 

1. 修复元素 Ai 并考虑其作为子序列中最终剩余元素的角色。 为了让 Ai 成为最终的幸存者，我们选择其左侧和右侧的任何元素子集，但我们必须确保它被包含在内。 
2. 如果我们将 Ai 视为幸存者，那么在此过程中，每个其他选定的元素都将其价值贡献给 Ai 一次，因为它们中的每一个最终都会被出售，并且其价值会添加到包括 Ai 在内的所有剩余元素中。 
3. 这意味着，如果 Ai 是所选子序列 S 的最终幸存者，则对 Ai 贡献的值是 S 中所有元素的总和。因此，无论顺序如何，子序列的值只是其元素的总和，因为最优策略确保完全累积到最后一个幸存者。 
4. 然后，问题就简化为对所有非空子序列求和，即该子序列中的元素之和。 
5. 现在我们交换求和顺序。 每个元素 Aj 对包含它的每个子序列都有贡献。 如果我们计算有多少个子序列包含 Aj，我们可以将其乘以 Aj 以获得其对最终答案的总贡献。 
6. 为了计算包含 Aj 的子序列，我们修复 Aj 的包含，并独立选择剩余 n − 1 个元素的任何子集。 这给出了包含 Aj 的 2^(n−1) 个子序列。 
7. 因此，Aj 对最终答案的总贡献为 Aj × 2^(n−1)。 对所有 j 求和得出最终结果。 

### 为什么它有效

 关键的不变量是，该过程总是将任何有效的排序转换为所有选定元素的完全累积到最终幸存者中，每个元素一次。 该订单仅影响中间状态，而不影响传输的总量。 这使得子序列值仅取决于所选元素的多重集，而不取决于销售订单，从而将优化分解为纯粹的组合和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    maxn = 200000
    
    # precompute powers of 2 up to maxn
    pow2 = [1] * (maxn + 1)
    for i in range(1, maxn + 1):
        pow2[i] = (pow2[i - 1] * 2) % MOD

    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        
        s = sum(arr) % MOD
        ans = s * pow2[n - 1] % MOD
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案依赖于 2 的预计算能力，因为每个元素恰好出现在 2^(n−1) 个子序列中。 对于每个测试用例，我们只需要数组的总和，然后乘以正确的组合因子。 

一个常见的实现陷阱是忘记在测试用例中重用预先计算的幂，这会将复杂性推向 O(nT)。 另一个是在乘以大的中间值时正确处理模数，特别是因为总和和幂都可能接近 998244353。

 ## 边缘情况

 对于像 [7] 这样的单元素数组，该算法计算 sum = 7 并乘以 2^0 = 1，产生 7，这与唯一子序列是元素本身的事实相匹配。 

对于全零数组，例如 [0, 0, 0, 0]，无论顺序如何，总和为零，并且每个子序列值都为零，因此即使有 15 个非空子序列，最终结果也正确为零。 

对于像 [5, 5, 5] 这样的重复值，每个位置都是独立处理的。 该算法不会合并相同的值，因此每个值贡献 5 × 2^(n−1)，并且总和正确反映了位置贡献而不是重复值删除，这是子序列定义所要求的。
