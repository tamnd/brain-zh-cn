 ## 解决方案
 # 问题理解

 这个问题要求我们将公寓单元放置在`r`经过`c`矩形网格。 一套公寓占据一个方格，两套公寓不得放置在相互接触的方格中。 触摸包括所有八个方向：水平、垂直和对角邻居。 

任务是计算存在多少个不同的有效放置集。 如果至少一个正方形在一种布置中包含公寓，但在另一种布置中不包含公寓，则两种布置是不同的。 空安排也是有效的。 答案可能非常大，因此必须以模数形式打印`10^9 + 7`。 

输入仅包含两个整数，即网格的行数和列数。 行数很少，最多10行，而列数可以达到1000。这种不对称是主要线索。 指数依赖于行数的解决方案是可行的，但指数依赖于列数的解决方案是不可能的。 由于无法通过尝试所有列选择来处理具有 1000 列的网格，因此我们需要一次处理一列。 

思考极限的有用方法`r <= 10`是一列只有`2^r`可能的占用模式。 对于 10 行，这只有 1024 个掩码，在删除垂直相邻公寓的无效掩码后，这个数字变得更小。 这使得状态压缩方法变得可行。 对每个方格进行天真的搜索将会得到`2^(r*c)`可能性，即使对于小网格来说也是天文数字。 

棘手的情况大多是由于忘记了禁止的邻居方向之一而引起的。 

例如，具有两行的单列：```
Input:
2 1
```正确的输出是：```
3
```可能的排列是空的、顶部方块被占用或底部方块被占用。 仅检查水平冲突的粗心解决方案可能会计算两个已占用的方格并错误地返回 4。 

另一个常见的错误是忽略对角线冲突。 例如：```
Input:
2 2
```正确的输出是：```
5
```唯一的非空有效排列恰好包含一个公寓，因为 2 x 2 网格中的每一对方块都相互接触。 仅阻止并排和垂直邻居的解决方案将错误地允许对角线对。 

最小的网格也需要注意：```
Input:
1 1
```正确的输出是：```
2
```有两种可能性：什么都不建或建一套公寓。 错误地初始化动态编程数组的实现可能会意外返回零。 

# 方法

 直接的做法是独立考虑每个广场并决定是否在那里放置公寓。 对于一个网格`r * c`平方，这给出`2^(r*c)`可能的安排。 该方法在逻辑上是正确的，因为它会检查所有可能的展示位置集并仅保留有效的展示位置，但它会立即变得无法使用。 即使只有 10 行和 20 列的网格也已经有`2^200`的可能性。 

暴力破解失败的原因并不是网格没有结构。 重要的观察是柱之间的相互作用是有限的。 当我们决定一列的内容时，有关前一列的唯一需要的信息是前一列的占用模式。 我们不需要记住整个历史。 

列可以表示为位掩码。 少量`i`如果行则为一`i`该列中包含一个公寓。 首先，我们丢弃具有两个相邻设置位的掩码，因为它们代表同一列内垂直接触的公寓。 

然后我们从左到右处理列。 对于每对连续的列掩码，我们检查它们是否冲突。 如果公寓出现在相邻列的同一行、上方一行或下方一行，则两列冲突。 如果它们不冲突，则两列可以以有效的排列连续出现。 

蛮力之所以有效，是因为每个完整的放置都是一系列列选择。 它失败了，因为序列数量巨大。 观察到只有相邻列相互影响，这让我们可以用一个小的动态编程状态替换完整的历史记录。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^(r*c)) | O(2^(r*c)) | O(r*c) | 太慢了|
 | 最佳| O(c * S^2) | O(c * S^2) | O(S)| 已接受 |

 这里，`S`是有效列掩码的数量。 为了`r = 10`,`S`只有144。 

# 算法演练

 1. 生成每个可能的列掩码`0`到`2^r - 1`。 仅保留没有两相邻行都被占用的掩码。 这些是单列唯一可能的状态，因为一列内禁止垂直触摸。 
2. 预先计算哪些有效掩码对可以并排放置。 当两个掩模没有共同占用的行并且没有移位一个位置的占用行时，这两个掩模是兼容的。 移位表示相邻列之间的对角线接触。 
3. 将第一列的每个有效掩码的动态编程值初始化为`1`。 每个掩码代表一个可能的第一列排列。 
4. 将剩余的列一一处理。 对于每个当前列掩码，添加从前一列中的每个兼容掩码到达它的方式数量。 前面的列不再重要，因为所有未来的冲突只涉及当前的最后一列。 
5. 将最后一列之后的所有动态规划值相加。 每个可能的最终列状态都代表一个完整的有效网格排列。 

为什么它有效：不变的是在处理任意数量的列之后，`dp[mask]`等于那些已处理列的有效排列数，其中最后一列具有完全相同的占用模式`mask`。 转换仅允许不违反任何接触规则的列对，因此它永远不会创建无效的排列。 每个有效排列都有一个唯一的列掩码序列，并且会考虑该序列中的每个转换，因此每个有效排列都会被精确计数一次。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve():
    r, c = map(int, input().split())

    masks = []
    for mask in range(1 << r):
        if (mask & (mask << 1)) == 0:
            masks.append(mask)

    n = len(masks)

    transitions = [[] for _ in range(n)]
    for i in range(n):
        a = masks[i]
        for j in range(n):
            b = masks[j]
            if (a & b) == 0 and (a & (b << 1)) == 0 and (a & (b >> 1)) == 0:
                transitions[i].append(j)

    dp = [1] * n

    for _ in range(1, c):
        ndp = [0] * n
        for prev in range(n):
            value = dp[prev]
            if value:
                for nxt in transitions[prev]:
                    ndp[nxt] += value
                    if ndp[nxt] >= MOD:
                        ndp[nxt] -= MOD
        dp = ndp

    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```第一部分构建合法列状态列表。 支票`(mask & (mask << 1)) == 0`删除垂直相邻的占用方块的蒙版。 将掩码移动一行就足够了，因为只有连续的行可以垂直接触。 

转换结构比较每对有效状态。 表达式`(a & b)`水平捕获直接相邻的公寓。 两个移位比较捕获对角邻居。 掩码被索引而不是直接存储在动态编程数组中，这使得转换保持紧凑。 

动态编程循环从已处理的一列开始。 每个状态都有一种作为第一列存在的方式，包括空状态。 接下来的每一列都会创建一个新数组，因为先前的值必须完全代表前一列，从而避免不同迭代中的状态意外混合。 

Python整数不会溢出，但加法后仍然需要求模运算，因为答案呈指数增长。 最终总和包括每个可能的结束列状态，包括空列。

# 测试用例```python
import sys, io

MOD = 10 ** 9 + 7

def solution(inp):
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    r, c = map(int, sys.stdin.readline().split())

    masks = []
    for mask in range(1 << r):
        if (mask & (mask << 1)) == 0:
            masks.append(mask)

    n = len(masks)
    trans = [[] for _ in range(n)]

    for i, a in enumerate(masks):
        for j, b in enumerate(masks):
            if (a & b) == 0 and (a & (b << 1)) == 0 and (a & (b >> 1)) == 0:
                trans[i].append(j)

    dp = [1] * n
    for _ in range(c - 1):
        ndp = [0] * n
        for i, val in enumerate(dp):
            for j in trans[i]:
                ndp[j] = (ndp[j] + val) % MOD
        dp = ndp

    ans = str(sum(dp) % MOD)
    sys.stdin = old_stdin
    return ans

assert solution("1 1\n") == "2", "minimum grid"
assert solution("2 2\n") == "5", "all cells touch in a 2x2 grid"
assert solution("1 5\n") == "13", "single row Fibonacci case"
assert solution("2 1\n") == "3", "vertical boundary case"
assert solution("3 3\n") == "35", "small multi-row grid"

 # 边缘情况

 对于输入：```
2 1
```生成的掩码是`00`,`01`， 和`10`。 由于只有一列，因此无需考虑水平过渡。 答案是有效单列掩码的数量，即 3。算法处理这个问题是因为初始动态编程数组已经代表了完整的网格，当`c = 1`。 

对于输入：```
2 2
```该算法创建相同的三列状态。 检查转换时，每对非空状态都会被拒绝，因为行重叠或移位掩码对角重叠。 只有涉及空状态的转换仍然存在，总共有五种排列。 这捕获了忘记对角线检查的实现。 

对于输入：```
1 5
```唯一的状态是空的和被占领的。 该转换仅在空状态之后才允许占用状态，因为两个相邻列不能同时包含公寓。 DP 在一条线上产生独立集合的序列，以 13 个排列结束。 

对于输入：```
1 1
```初始状态数组包含两种可能性。 由于不需要转换，因此最终答案只是初始状态的总和。 这证实了空置布置和单公寓布置均被计算在内。
