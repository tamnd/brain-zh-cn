 ## 解决方案
 ## 问题理解

 该任务是围绕对写为字符序列的给定数字进行简单的“幸运数字”检查而构建的。 您收到一个或多个输入，每个输入代表一个文本形式的数字，您必须根据涉及数字 7 的单一规则来决定该数字是否符合“幸运”的条件。 

每个输入的输出是一个短的判决字符串。 从概念上讲，您不是对数字执行算术运算，而是扫描其表示形式并确定特定字符是否出现在其中的任何位置。 

尽管计算听起来微不足道，但关键细节是数字可能足够大，以至于在某些语言中将其视为整数是不必要的，甚至是不安全的。 正确的心理模型是输入是字符串，任务是对字符进行模式检查。 

此类问题的约束通常很宽松。 即使多个测试用例中每个输入字符串的长度达到 10^5，每个测试用例的线性扫描仍然是最佳的。 任何尝试重复转换、嵌套扫描或算术分解的方法都将保持线性，但会带来不必要的开销，而没有任何好处。 

主要的边缘情况源于数字的表示方式。 一个幼稚的实现可能会假设一个整数输入并直接转换它，当值超过典型的整数限制时，它会默默地中断。 例如，像这样的输入`777777777777777777777`如果解析不正确，在固定宽度整数语言中会溢出，但作为字符串它是完全有效的。 另一个微妙的情况是前导零，例如`00017`，其中数字 7 仍然存在，并且无论格式化如何都必须被检测到。 

不存在像多个数组或图这样的结构复杂性。 整个问题归结为正确的输入处理和精确的字符扫描。 

## 方法

 最直接的方法是将数字视为字符串并检查字符是否`7`出现在任何地方。 这可以通过从左到右扫描字符串并在出现一个字符时立即停止来完成。`7`遇到。 这种方法是正确的，因为条件仅取决于存在，而不取决于位置或频率。 

暴力心理模型可能会尝试以数字方式解释数字，并使用模 10 算术重复提取数字。 虽然这也可行，但没有必要，因为它需要重复的除法运算以及从字符串到整数形式的转换。 对于非常大的输入，转换步骤本身会成为瓶颈或溢出问题的根源。 

关键的观察结果是，当以文本形式提供输入时，基于数字的属性基本上是字符串属性。 一旦接受这一点，问题就简化为对字符的简单成员资格测试。 这允许在一次输入中获得最佳解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解（数字提取）| 每个数字的 O(d) 具有较高的恒定开销 | O(1) | O(1) | 已接受但没有必要 |
 | 最佳（字符串扫描）| 每个数字 O(d) | O(1) | O(1) | 已接受 |

 这里 d 是输入表示中的字符数。 

## 算法演练

 1. 读取测试用例的数量（如果存在），或处理输入行直至耗尽。 每行对应一个编码为字符串的数字。 这确保我们安全地处理任意大的值，而无需将它们解析为整数。 
2. 对于每个输入字符串，从左到右迭代其字符。 目标是检测任何字符是否等于`7`，因为这是决定输出的唯一条件。 
3. 如果`7`在扫描过程中遇到，立即将该数字分类为幸运并停止处理进一步的字符。 提前终止很重要，因为它可以避免长时间输入中不必要的工作。 
4. 如果扫描完成后没有遇到`7`，将数字分类为不吉利。 
5.输出对应的字符串，一般为`"Happy"`对于幸运数字和`"Sad"`否则。 

### 为什么它有效

 正确性取决于所测试的属性在数字的数字集中是存在的。 该算法在扫描过程中保持了一个简单的不变量：处理完前k个字符后，我们正确地确定了是否有任何`7`存在于该前缀中。 如果在任何一点`7`找到后缀不能使结果无效，因此提前终止可以保持正确性。 如果扫描完成，则不变量确保没有数字`7`存在于字符串中的任何位置，因此保证给出否定答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    if not s:
        return
    if '7' in s:
        print("Happy")
    else:
        print("Sad")

if __name__ == "__main__":
    solve()
```该解决方案将输入读取为原始字符串，并完全避免任何整数解析。 会员资格检查`'7' in s`在 Python 中高效实现，并在内部执行线性扫描并提前退出。 

这里的主要实现选择是故意避免整数转换。 这消除了所有溢出风险，并使逻辑与问题的实际结构保持一致。

 ## 边缘情况

 一种重要的边缘情况是输入完全由 7 以外的重复数字组成，例如`11111111`。 该算法扫描完整字符串并正确返回`"Sad"`因为没有出现匹配的字符。 

另一种情况是字符串非常长并且数字`7`出现在最后，例如`99999999999999999997`。 该算法不会假设早期成功，并且仍然正确扫描直到最终字符，从而确保最坏情况输入的正确性。 

第三种情况是带有前导零的输入，例如`0000070`。 这些不会影响逻辑，因为每个角色都被平等对待，并且存在`7`无论位置或格式如何，仍然会被检测到。
