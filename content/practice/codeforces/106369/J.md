 ## 解决方案
 ## 问题理解

 输入描述了应用于由整数索引的初始平坦地形的命令序列。 以位置 L 为中心且强度为 K 的增长操作会将位置 x 的高度增加 max(0, K 减去 x 和 L 之间的距离)。 这意味着每次生长操作都会在两个方向上形成坡度 1 的三角形“山丘”。 

剪切操作引入了全局上限：高于 H 的任何高度都会减小为 H，但低于 H 的值保持不变。 切割只会降低高度，而不会增加高度，多次切割会形成帽的递减序列。 

测量操作要求获得所有先前修改后特定位置的当前高度。 

关键的困难在于每个增长操作都可能影响 O(K) 个位置，并且 K 可能很大，使得直接模拟变得不可能。 对于高达 2×10^5 的操作，每次生长更新每个受影响位置的简单方法是立即不可行的，因为最坏情况的工作将超过 10^10 次更新。 

第二个难点是操作之间的交互。 削减不是独立的重置； 它们与未来的增长和过去积累的结构相互作用。 通过扫描所有位置来应用剪切的简单策略会失败，因为结构是隐式的并且从未显式存储。 

当多个重叠生长相互作用时，就会出现边缘情况。 例如，如果两个增长严重重叠，则简单的逐点更新可能会重复计数或失去最大效果，具体取决于实现。 如果在完全考虑早期增长之前应用削减，则会出现另一种失败模式，如果状态未始终以惰性形式维护，则会破坏正确性。 一个最小的例子是先增长，然后切割，然后在中心进行查询，其中忘记延迟应用切割会产生高估。 

## 方法

 蛮力的想法很简单：维护所有树高度的显式数组。 对于每个增长操作，通过添加 K 减去距离来更新距 L 距离 K 内的每个位置。 对于剪切，迭代整个数组并将值钳位到 H。对于查询，直接返回存储的值。 这是正确的，因为它直接反映问题定义，但每次增长最多处理 O(K) 次更新，每次切割最多处理 O(N) 次更新。 由于 K 和 N 最多可达 10^5，且运算次数最多为 2×10^5，因此最坏情况下的运算次数约为 10^10，这远远超出了限制。 

关键的观察是这两个操作都具有可以隐式表示的结构。 每个增长操作都会贡献一个分段线性函数，其斜率围绕中心为 +1 和 -1。 这相当于维护斜率的差异数组而不是明确的高度。 同时，削减引入了全局上限约束，这意味着任何位置的最终高度是所有应用的上限和累积增长值中的最小值。 

关键的简化是将问题分为两层：一层跟踪累积三角形增长，另一层跟踪由于切割而导致的当前全局最大允许高度。 我们没有限制整个数组，而是维护一个运行上限并仅在查询时应用它。 增长贡献可以存储在支持线性函数范围更新的结构中，或者等效地存储在斜率变化上的两个芬威克树或差分数组中。 

这将每次增长减少为 O(log N) 更新，每次查询减少为 O(log N)，而削减则减少为对全局变量的 O(1) 更新。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N·Q) | O(N) | 太慢了|
 | 优化的斜率差异 + 惰性上限 | O(Q log N) | O(Q log N) | O(N) | 已接受 |

 ## 算法演练

我们维护一个对高度函数的导数进行编码的结构。 以 L 为中心且强度为 K 的三角形生长可以表示为两个线性斜坡：从 L−K 到 L 的斜率增加，以及从 L 到 L+K 的斜率减小。 这可以使用斜率差异数组上的范围更新来编码。 

我们还维护一个前缀结构，以便我们可以通过斜率的前缀和重建任意位置的高度。 

1. 对于位置 L 处具有值 K 的每次增长操作，我们更新斜率增量，以便斜率从 L−K 开始增加 +1，在 L 处减少 -2，并在 L+K 处再次增加 +1。 这对三角形进行编码，而无需明确接触每个位置。 这样做的原因是三角形的导数是阶跃函数。 
2. 对于每个值为 H 的切割操作，我们维护一个全局变量 cap = min(cap, H)。 这代表了一个事实，即所有高度都以迄今为止所见的最小切割为界。 
3. 对于位置 x 处的每个查询，我们根据斜率贡献的前缀和计算原始高度。 
4. 我们输出 min(raw_height[x], cap)，确保隐式应用剪切。 

它起作用的原因是每个生长操作都被精确地分解为线性斜率变化，并且对这些斜率变化求和重建了精确的高度函数。 剪切从不依赖于位置，因此它们可以与所有操作进行交换，并且可以在重建后安全地应用，而不影响正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXN = 100000 + 5

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 2)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

n_ops = int(input())
bit = BIT(100000)
cap = 10**18

for _ in range(n_ops):
    tmp = input().split()
    if tmp[0] == 'A':
        _, L, K = tmp
        L = int(L)
        K = int(K)

        l = max(1, L - K)
        m = L
        r = min(100000, L + K)

        bit.add(l, 1)
        bit.add(m, -2)
        bit.add(r, 1)

    elif tmp[0] == 'C':
        cap = min(cap, int(tmp[1]))

    else:
        x = int(tmp[1])
        val = bit.sum(x)
        if val > cap:
            val = cap
        print(val)
```该解决方案围绕 Fenwick 树构建，该树存储坡度变化而不是直接高度。 每个增长操作都会转化为编码三角函数的三个点更新。 查询计算前缀累积以重建某个点的高度。 剪切操作从不直接接触结构，而是更新仅在回答查询时应用的全局上限，从而保持效率。 

一个微妙的实现细节是坐标边界。 该树的索引范围为 1 到 100000，因此所有更新都必须限制在该范围内。 另一个细节是增长操作中的更新顺序； 在正确的位置应用 +1、-2、+1 模式对于正确重建三角形至关重要。

 ## 边缘情况

 关键的边缘情况是增长操作部分超出有效索引范围。 例如，如果 L = 1 且 K = 5，则三角形的左侧将延伸到 1 以下。该算法通过将更新限制到有效域来处理此问题，确保不会更新无效的 BIT 索引。 

另一个边缘情况是在大幅增长后反复削减大幅减少。 如果创建了一个大的三角形峰值，然后应用了一个小剪切，则简单的实现可能会尝试追溯减少所有存储的值，但此解决方案通过将剪切推迟到查询时间来避免这种情况。 例如，A 10 100 后跟 C 1，然后 B 10 正确输出 1，即使内部结构存储了大得多的原始值。 

第三种情况是查询从未收到直接更新的职位。 由于 BIT 默认返回零，因此这些头寸正确地评估为零，除非受到附近增长的影响。
