 ## 解决方案
 ## 问题理解

 游戏从以下数字的排列开始`1`到`n`。 两名玩家重复选择两个不正确的位置并交换这些位置的值。 到达其自身位置的值将被锁定，并且不能参与以后的交换。 执行交换并最终使整个排列排序的玩家获胜。 抽烟的乔先行动了。 

输入包含排列的大小和值的当前排列。 输出询问哪个玩家有获胜策略，假设两个玩家都选择了最大化获胜机会的动作。 

主要限制是`n`可以达到`10^6`。 这立即排除了模拟、状态动态规划或任何尝试探索可能移动的方法。 可能的排列数量是巨大的，因此解决方案必须提取起始排列的数学属性并在线性时间内计算它。 

棘手的部分是，玩家可以进行不会立即改善排列的交换。 仅计算排序所需的最小交换次数的解决方案是不够的。 例如，排列```
3
2 3 1
```可以在两次交换中排序，因此粗心的方法可能会说第二个玩家获胜。 然而，真正的原因更深层次：每个以排序排列结束的有效游戏都具有相同的移动奇偶性。 最小交换次数恰好与此处的奇偶校验相匹配，但证明必须考虑所有可能的选择。 

另一个边缘情况是由几个独立循环组成的排列。 例如：```
4
4 3 2 1
```正确的输出是：```
Oh No!
```排列与通常意义上的排序相差两次交换。 由于排列的总奇偶性是偶数，因此达到排序状态所需的移动次数也必须是偶数，这意味着第二个玩家获得最终的移动。 

最后一个常见错误是错误地处理已经正确的位置。 考虑：```
3
1 3 2
```第一个位置已经固定，无法触及。 剩下的两个头寸形成一个互换，所以答案是：```
Smokin Joe!
```将所有职位都计为可用的实现不会反映实际规则。 

## 方法

 直接的方法是对决斗本身进行建模。 从当前的排列中，我们可以生成可移动位置之间的所有可能的交换，递归地解决每个结果状态，并标记当前玩家可以强制获胜的状态。 这是正确的，因为它遵循确切的游戏规则。 

问题在于州的数量。 长度的排列`n`可以有`n!`不同的安排，甚至一个国家也可以有多种可能的交换。 为了`n = 10^6`，即使检查一次所有可能的交换也已经是不可能的了。 

关键的观察来自于排列奇偶性。 每次交换都会改变排列的奇偶校验。 排序后的排列是恒等排列，它始终具有偶校验。 因此，如果初始排列具有奇数奇偶校验，则达到排序状态的每条路径都必须包含奇数个移动。 如果它具有偶数奇偶性，则每条路径都必须包含偶数个移动。 

锁定规则不会改变此参数。 锁定元素只是当前排列的固定点。 每个合法的举动仍然是两个当前可移动位置的换位，因此它仍然会翻转平价。 由于游戏必须以恒等排列结束，因此在第一步之前就已经确定了步数的奇偶性。 

如果步数必须是奇数，则第一个玩家进行最后一步。 如果必须是偶数，则第二个玩家这样做。 

排列的奇偶性可以从其循环分解中找到。 一个周期的长度`k`贡献`k - 1`交换到奇偶校验，因此总奇偶校验为：```
(n - number_of_cycles) mod 2
```找到周期需要线性时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n! * n) | O(n! * n) | O(n!) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 遍历排列并计算它包含多少个循环。 从未访问过的位置开始，重复遵循存储在那里的值，直到返回到访问过的位置。 标记每个访问过的位置一次即可给出线性时间内的所有循环。 
2. 计算`n - cycles`。 每个周期的长度`k`需要`k - 1`转置分解为固定点，因此将所有循环上的这些值相加即可得出排列符号的指数。 
3. 检查该值的奇偶性。 奇数值意味着起始排列具有奇数奇偶性，因此每个有效游戏都有奇数次交换，并且 Smokin Joe 做出最后一步。 
4. 如果该值是偶数，则每个有效游戏都有偶数次交换，并且亡命之徒做出最后一步。 

为什么它有效：

 不变量是排列的奇偶性。 交换总是会改变奇偶校验，因为每次转置都会反转排列的符号。 唯一的最终状态是已排序的排列，其奇偶性是偶数。 因此，在任何已完成的决斗期间进行的交换次数的奇偶性必须与排列的初始奇偶性完全匹配。 由于玩家只决定播放哪个有效序列，而不是其长度的奇偶性，因此获胜者完全由初始排列决定。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    visited = [False] * n
    cycles = 0

    for i in range(n):
        if not visited[i]:
            cycles += 1
            cur = i
            while not visited[cur]:
                visited[cur] = True
                cur = p[cur] - 1

    if (n - cycles) & 1:
        print("Smokin Joe!")
    else:
        print("Oh No!")

if __name__ == "__main__":
    solve()
```该数组使用从零开始的索引存储，因此该值`p[cur]`被转换为`p[cur] - 1`当遵循一个循环时。 周期计数是唯一需要的信息，因此无需修改排列或模拟交换。 

这`visited`数组可防止重复遍历同一循环。 每个位置只输入一次，这就是为什么即使对于最大输入大小，遍历也保持线性。 

最终条件使用奇偶校验`n - cycles`。 这个数量可能很大，但 Python 整数可以安全地处理它。 只有最低位很重要，因此请检查`& 1`避免不必要的工作。

 ## 边缘情况

 对于输入```
3
1 3 2
```第一个位置已经正确，因此唯一的活动周期是位置二和位置三之间的交换。 该算法总共找到两个周期，计算`3 - 2 = 1`，并预测奇数步。 第一个玩家获胜。 

对于输入```
4
4 3 2 1
```该排列包含两个长度为 2 的独立循环。 每个周期为交换平价贡献 1，总共为 2。 该算法计算出一个偶数，这意味着最后一步属于第二个玩家。 

对于具有许多固定点的已经几乎排序的排列，例如```
5
1 2 3 5 4
```循环遍历自然会忽略固定位置，因为每个固定位置只是一个长度为 1 的循环。 只有重要的交换会影响奇偶校验计算，因此答案仍然是正确的。
