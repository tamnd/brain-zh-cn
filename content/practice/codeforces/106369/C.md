 ## 解决方案
 ## 问题理解

 该任务描述了一个小系统，该系统在一行位置上逐步演化，其中每个位置最初保存一些表示堆栈大小的整数值。 该行的行为就像一个序列，通过相邻元素之间的局部交互重复修改。 

在每一步中，只要序列不是非递减顺序，我们就会定位一对相邻位置，其中左值严格大于右值。 当选择这样的对时，两个元素交换位置，交换后，新的右侧元素立即通过加法吸收新的左侧元素的值。 这意味着每个操作都改变顺序，并且以定向方式合并来自交换元素的信息。 

输出是无法应用更多有效操作后序列的最终状态，这意味着数组在流程约束下按非降序排序。 

尽管该声明看起来像局部交换规则，但积累的存在使得演化变得不平凡。 值不仅会移动，还会在传递更小的元素时增长。 

从复杂性的角度来看，序列长度可能足够大，如果单独处理每个步骤，则直接模拟交换变得不可行。 简单的模拟可能需要重复扫描和执行相邻交换，从而导致二次或更差的行为，具体取决于存在多少反演。 这立即表明，预期的解决方案必须推理重复局部交换的全局影响，而不是逐一执行它们。 

当较大的值被较小的值包围时，会出现微妙的边缘情况。 例如，考虑一个像这样的数组`[5, 1, 2, 3]`。 天真的方法可能会改变`5`一步步向右，但每次交换也会增加相邻值，这会改变后续的比较。 另一种情况是`[2, 1, 3]`，其中第一次交换通过累加间接修改第三个元素，这意味着最终结果不仅仅是和的排序排列，而是取决于交互顺序。 

这些示例表明，将交换视为独立反转是不正确的，因为每个操作都会以影响未来有效移动的方式永久修改值。 

## 方法

 蛮力方法直接模拟所描述的过程。 我们从左到右重复扫描数组，找到任意索引`i`这样`a[i] > a[i+1]`，执行交换，然后将新的左值添加到新的右值中。 每个操作都会减少反转次数，但不一定会减少可预测的数量，因为值本身会发生变化。 

在最坏的情况下，每次交换一次仅将一个大元素移动一个位置，并且每次移动可能需要以级联方式更新值。 和`n`元素，最多可以有`O(n^2)`交换，并且每次遍历数组都会花费`O(n)`，导致`O(n^3)`直接实现中的行为。 即使进行了优化，对数组的重复重新扫描也使得这种方法无法用于大型输入。 

关键的观察结果是，该过程总是将较大的元素向右移动，当它们经过较小的元素时，这些较小的元素有效地被吸收到移动值中。 这表明最终的配置取决于每个元素如何累积其超越元素的贡献，而不是交换的确切顺序。 

我们可以将这个过程解释为每个元素最终收集所有在其稳定之前位于其右侧的较小元素，而不是模拟交换。 这将问题转化为计算每个位置一旦到达最终排序位置将带来的总贡献。 排序过程本身变得无关紧要； 只有积累结构才重要。 

这产生了一个有效的解决方案，我们使用贪婪或基于堆栈的反转解释来跟踪值如何传播和组合，以结构化方式解决，确保每个元素被处理一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(n3) | O(n) | 太慢了|
 | 累积单遍逻辑 | O(n) 或 O(n log n) 取决于实现 | O(n) | 已接受 |

 ## 算法演练

 我们处理数组的同时保持这样的想法：被右侧较小元素“阻挡”的元素最终将合并为单个有效值。 

1. 我们从左到右迭代数组，将每个元素视为可能吸收先前块的潜在“最终块”。 

选择这个方向是因为在交换期间合并总是向右传输值，因此向右处理自然反映了最终的累积。 
2. 在解决所有先前的局部违规之后，我们维护一个表示当前有效序列的结构。 每个存储的值都代表一个块，该块已经吸收了早期元素中所需的所有内容。 
3. 对于每个新元素，我们将其与该结构中的最后一个块进行比较。 如果最后一个块大于当前元素，则意味着原始过程中会发生交换合并，因此我们通过添加它们的值将它们合并为单个块。 

此步骤将多个交换操作压缩为一次算术更新，因为同一对区域之间的重复交换仅累积值，而不会改变解析后的相对顺序。 
4. 只要最后一个块仍然大于当前元素，我们就重复合并，因为单个元素可能会级联多个先前的块。 
5. 一旦无法再合并，我们将当前元素作为新的独立块追加。 

处理完所有元素后，该结构包含所有隐式交换和合并后的最终状态。 

### 为什么它有效

 关键的不变量是，所维护的结构始终表示一种状态，其中没有相邻对违反变换规则下的非递减条件。 每次合并两个块时，我们都会准确模拟原始过程中这些段之间发生的所有交换的效果，包括累积的添加。 因为合并总是消除一个反转，并且永远不会在左侧创建新的反转，所以每个元素仅被最终确定一次，并且其累积值与所有有效交换操作终止后的值相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))

    stack = []

    for x in a:
        while stack and stack[-1] > x:
            x += stack.pop()
        stack.append(x)

    print(*stack)

if __name__ == "__main__":
    solve()
```该解决方案使用堆栈来表示数组当前的压缩状态。 每个传入元素都会附加或合并到先前的块中。 while 循环至关重要，因为单个合并可能会暴露与早期元素的新冲突，因此我们不断解决，直到达到稳定性。 

一个常见的错误是每个元素只执行一次合并，这在像这样的链上会失败`5, 4, 3, 2`，其中需要完全级联合并才能正确累积所有值。 

最终的打印输出稳定的序列，该序列对应于所有交换和合并操作都用尽后的数组。

 ## 边缘情况

 对于像这样的单元素输入`1\n7`，堆栈逻辑追加一次并立即终止，产生`7`，与不可能进行交换的事实相匹配。 

对于严格递减序列，例如`5 4 3 2 1`，每个新元素都会触发完全折叠到前一个堆栈中，反复合并直到只剩下一个值。 跟踪这个显示了不变式，即处理每个前缀后，堆栈包含完全解析的状态，在合并规则下没有相邻反转，因此最终输出成为所有元素的总和。 

对于类似排序的序列`1 2 100 3 4`，大值`100`保持稳定，直到它在右侧遇到较小的值，然后按顺序吸收它们。 堆栈确保一旦`100`合并于`3`，它可能会触发进一步合并`2`或者`1`取决于排序，但每个元素仍然只处理一次，在有效处理局部无序的同时保持正确性。
