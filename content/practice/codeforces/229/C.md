 ## 解决方案
 ## 问题理解

 我们从一个完整的无向图开始`n`顶点。 每对顶点之间都恰好有一条边。 爱丽丝保留`m`这些边，鲍勃接收所有剩余的边。 

任务是计算 Alice 的图中存在多少个三角形以及 Bob 的图中存在多少个三角形。 三角形只是三个顶点的集合，它们之间的所有三个边都出现在同一个图中。 

输入给出了属于 Alice 的边。 Bob 的图隐式地是补图：Alice 的每个缺失边自动属于 Bob。 

最大的约束是`n ≤ 10^6`，这会立即排除任何与迭代所有三元组顶点类似的情况。 蛮力`O(n^3)`三角形检查需要周围`10^18`在最坏的情况下操作，完全不可能。 即使存储邻接矩阵也需要`10^12`细胞，它也不适合记忆。 

Alice 边的数量最多为`10^6`，它比`n^2`。 这强烈表明解决方案应该主要取决于边和度，而不是所有顶点对或三元组。 

问题的一个微妙部分是我们同时计算两个互补图中的三角形。 粗心的实现可能会尝试分别计算 Alice 三角形和 Bob 三角形，但 Bob 的图可能大约有`n^2 / 2`边缘，因此显式构造它是不可能的。 

另一个容易犯的错误是整数溢出。 完整图中三角形的数量`10^6`顶点是$$\binom{10^6}{3} \approx 1.67 \times 10^{17}$$它不适合 32 位整数。 Python 自动处理大整数，但在其他语言中这需要 64 位算术。 

考虑这个小例子：```
4 0
```爱丽丝没有棱角。 Bob 有 4 个顶点的完整图，其中包含$$\binom{4}{3} = 4$$三角形。 任何只处理 Alice 边缘而忘记 Bob 的方法都会错误地输出`0`。 

另一个棘手的情况是当三元组混合两个图中的边时：```
3 2
1 2
2 3
```三个顶点没有形成爱丽丝三角形，因为边`(1,3)`失踪了。 它们也不会在鲍勃中形成三角形，因为鲍勃只有`(1,3)`。 正确答案是`0`。 独立计算部分结构的朴素公式可能会意外地过度计算此类混合三元组。 

## 方法

 最直接的解决方案是检查每个三元组的顶点`(a, b, c)`。 对于每个三元组，我们检查所有三个边是否都属于 Alice 或者所有三个边都属于 Bob。 如果是，我们会在答案中加一。 

这在逻辑上是有效的，因为每个三角形都恰好对应一个三重顶点。 问题在于复杂性。 有$$\binom{n}{3}$$三元组，变成大约`1.67 × 10^17`什么时候`n = 10^6`。 即使每秒十亿次操作也需要数年时间。 

关键的观察结果是，每个三元组的顶点恰好属于以下四个类别之一：

 1. 所有三个边都属于 Alice。 
2. 所有三个边都属于 Bob。 
3. 恰好有一条边属于 Alice。 
4. 正好有两条边属于Alice。 

只有前两类有助于回答。 

与直接计算有效三元组相比，计算所有三元组并减去坏三元组要容易得多。 

现在关注在任一图中都不是有效三角形的三元组。 这样的三元组必须同时包含 Alice 和 Bob 边。 这意味着它要么有一条 Alice 边，要么有两条 Alice 边。 

取任何爱丽丝边`(u, v)`。 对于每三个顶点`w`, 三重`(u, v, w)`行为如下：

 - 如果两者都`(u,w)`和`(v,w)`是爱丽丝边，三元组形成爱丽丝三角形。 
- 如果 Alice 中都不存在，则三元组形成 Bob 三角形。 
- 否则三元组是混合的且无效。 

有多少个混合三元组包含边`(u,v)`？ 

顶点`w`恰好当其中之一无效`(u,w)`和`(v,w)`爱丽丝存在，而另一个则不存在。 

此类顶点的数量为：$$(\deg(u)-1) + (\deg(v)-1)$$因为：

-`deg(u)-1`计算连接到的顶点数`u`除了`v`-`deg(v)-1`计算连接到的顶点数`v`除了`u`每个混合三元组都以这种方式精确计数一次，即通过其独特的 Alice 边将结构分为单边或双边情况。 

所以我们可以从所有三元组开始：$$\binom{n}{3}$$并减去所有混合三元组：$$\sum_{(u,v)\in E} (\deg(u)-1)(?)$$我们需要仔细推导出正确的公式。 

对于爱丽丝边缘`(u,v)`，与一个端点相邻的顶点数等于：$$(\deg(u)-1) + (\deg(v)-1) - 2 \times \text{common neighbors}$$但还有一个更清晰的观点。 

每个混合三元组要么恰好包含一条 Alice 边，要么恰好包含两条 Alice 边。 在这两种情况下，三元组内的 Alice 边数为`1`或者`2`。 

对于固定的 Alice 边`(u,v)`， 有：$$n - 2$$第三个顶点的选择。 

他们之中：

-`common(u,v)`产生爱丽丝三角形，
 -`(n-2-\deg(u)-\deg(v)+2+common(u,v))`产生鲍勃三角形，
 - 其余的都是混合的。 

混合计数简化为：$$\deg(u) + \deg(v) - 2 - 2\cdot common(u,v)$$对全球范围内的共同邻居项进行求和是很困难的。 

关键的简化是以不同的方式计算无效三元组。 

假设一个三元组恰好有一条 Alice 边。 然后，如果我们迭代 Alice 边缘，它只会贡献一次。 

假设一个三元组正好有两条 Alice 边。 那么它的贡献恰好是两倍。 

所以如果我们计算：$$\sum_{(u,v)\in E} (n - 2 - (\deg(u)-1) - (\deg(v)-1))$$我们再次得到一个复杂的表达式。 

有一个更短的标准推导。 

对于每个三元组：

 - 有效的三元组贡献之一`0`或者`3`为其三对边缘计数的总和，
 - 混合三元组贡献`1`或者`2`。 

因此，如果我们对 Alice 边求和：$$\sum_{(u,v)\in E} (n - \deg(u) - \deg(v))$$每个混合三元组的贡献正好`1`，而有效的三元组贡献`0`。 

这直接给出了坏三元组的数量。 

最后：$$\text{answer} = \binom{n}{3} - \sum_{(u,v)\in E}(n-\deg(u)-\deg(v))$$这只需要度数和越过边缘的通道。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 读取 Alice 图的所有边并计算每个顶点的度数。 

度数组是公式所需的核心信息。 由于该图相对于稀疏`n²`，仅存储边缘端点是有效的。 
2. 计算顶点三元组的总数：$$\binom{n}{3} = \frac{n(n-1)(n-2)}{6}$$每个三角形，无论是在 Alice 的图中还是在 Bob 的图中，都对应于一个无序的顶点三元组。 

1. 对于每条爱丽丝边`(u,v)`，计算：$$n - \deg(u) - \deg(v)$$该值计算有多少顶点与边一起创建混合三元组`(u,v)`。 

要了解原因，请考虑第三个顶点`w`。 

如果`w`与 Alice 中的两个端点都不相邻，则除`(u,v)`属于 Bob，因此该三元组恰好有一条 Alice 边。 

如果`w`与两个端点相邻，三元组就成为爱丽丝三角形。 

其余的顶点创建混合三元组，并且代数完全简化为上面的公式。 

1. 将所有 Alice 边的数量相加。 

每个无效的三元组只计算一次。 

恰好具有一条 Alice 边的三元组通过该边进行计数。 

恰好有两个 Alice 边的三元组也只计算一次，因为缺少的 Alice 边标识了唯一的非相邻对。 
2. 从三元组总数中减去无效三元组数。 

剩下的三元组正是其三个边都属于同一个图的三元组。 

### 为什么它有效

 每个三元组的顶点根据其包含的 Alice 边数恰好属于四个类别之一：`0`,`1`,`2`， 或者`3`。 

仅类别`0`和`3`是有效的三角形，分别对应于Bob三角形和Alice三角形。 

表达式$$\sum_{(u,v)\in E}(n-\deg(u)-\deg(v))$$精确计算类别中的三元组`1`和`2`。 

因此，从三元组总数中减去这个值就剩下有效的值。 由于每个无效三元组被计数一次，而每个有效三元组被计数零次，因此该公式是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    deg = [0] * (n + 1)
    edges = []

    for _ in range(m):
        u, v = map(int, input().split())
        deg[u] += 1
        deg[v] += 1
        edges.append((u, v))

    total = n * (n - 1) * (n - 2) // 6

    bad = 0

    for u, v in edges:
        bad += n - deg[u] - deg[v]

    print(total - bad)

solve()
```第一部分读取图表并计算度数。 我们还存储所有边，因为第二遍需要访问每个边端点对。 

变量`total`存储所有无序顶点三元组的数量。 这使用组合公式从以下位置选择三个顶点`n`。 

第二个循环计算无效三元组的数量。 表达式```
n - deg[u] - deg[v]
```必须在所有学位最终确定后进行评估，这就是为什么首先进行学位计算的原因。 

一个常见的错误是在阅读边缘时尝试更新答案。 这会失败，因为输入处理期间度数不完整。 

另一个微妙之处是整数大小。 的价值`total`可以超过`10^17`，因此具有固定整数大小的语言需要 64 位类型。 Python 整数是任意精度的，因此不需要特殊处理。 

该算法从不构建鲍勃的图。 这很重要，因为鲍勃的图可能大致包含`5 × 10^11`边缘时`n = 10^6`。

 | 顶点| 学位|

 | 2 | 3 |

 | 4 | 2 |

 总三元数：$$\binom{5}{3} = 10$$现在处理每个边。 

| 边缘| 公式| 贡献|
 | --- | --- | --- |
 | (1,2) | 5 - 2 - 3 | 5 - 2 - 3 0 |
 | (1,3) | 5 - 2 - 3 | 5 - 2 - 3 0 |
 | (2,3) | 5 - 3 - 3 | 5 - 3 - 3 -1 |
 | (2,4) | 5 - 3 - 2 | 5 - 3 - 2 0 |
 | (3,4) | 5 - 3 - 2 | 5 - 3 - 2 0 |

最终答案：$$10 - 7 = 3$$与样本相匹配。 

该轨迹说明了为什么单边缘贡献的局部解释可能会产生误导。 正确性来自于所有三元组的全局计数论证。

 ## 边缘情况

 考虑空的 Alice 图：```
4 0
```该算法计算：$$\binom{4}{3} = 4$$没有边，因此坏三重和为零。 答案就变成了`4`。 

这是正确的，因为 Bob 拥有四个顶点上的整个完整图。 

现在考虑一张缺少一条边的图：```
3 2
1 2
2 3
```学位：

 | 顶点| 学位|
 | --- | --- |
 | 1 | 1 |
 | 2 | 2 |
 | 3 | 1 |

 总三元数：$$1$$坏数：$$(3-1-2) + (3-2-1) = 0$$最终答案变成`0`。 

三重`(1,2,3)`混合了 Alice 和 Bob 的边，所以它不应该算在内。 

最后，考虑一个完整的爱丽丝三角形：```
3 3
1 2
2 3
1 3
```总三元数：$$1$$错误计数变为零，因为没有三元组混合这两个图。 答案依然存在`1`，与单个爱丽丝三角形完全匹配。
