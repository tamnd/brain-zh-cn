 ## 解决方案
 ## 问题理解

 我们有一个二进制矩阵，其中每行都可以循环旋转。 左旋转将每个元素向左移动一个位置并将第一个元素包裹到末尾。 右旋转则相反。 

目标是使至少一列完全由`1`s，使用行移位的最小总数。 每一行可以独立移动，将一行移动一个位置需要一次移动。 

关键的观察结果是，除了通过选择最后一列之外，行之间不会相互作用。 如果我们决定该专栏`j`应该成为全部`1`s，那么每一行独立地贡献一些最小成本来放置一个`1`进入该专栏。 柱的总成本`j`是每行成本的总和。 

约束在一个维度上很小，在另一个维度上很大。 我们最多有`100`行，但最多`10^4`列。 解决方案围绕`O(n * m^2)`仍然可以接受，因为最坏的情况大约是`10^8`操作，已经接近Python的极限，存在风险。 任何立方体都是完全不可能的。 每行近线性扫描是目标。 

有一个特别重要的不可能条件。 如果某行不包含`1`无论如何，那么再多的循环移位也无法将`1`进入任何列。 这意味着答案立即`-1`。 

一个常见的错误是分别处理左移和右移，而不正确考虑环绕。 

例如：```
1 5
10000
```正确答案是`0`，因为列`0`已经包含一个`1`。 

如果我们定位列`4`，最小成本为`1`， 不是`4`，因为右移一次会变换`10000`进入`00001`。 

当仅计算一个方向的距离时，会出现另一个容易出现的错误。 

考虑：```
1 6
001000
```定位柱`0`应该花费`2`，因为左移两次会移动`1`来自索引`2`索引`0`。 单向扫描可能会错误返回`4`。 

还有一个微妙的环绕案例：```
1 5
00001
```定位柱`0`成本`1`，因为左移会将最后一个元素移动到前面。 忘记循环行为会错误地返回`4`。 

## 方法

 蛮力的想法很简单。 对于每个目标列`j`，独立尝试每一行并计算带来一些`1`进入专栏`j`。 

假设一行有一个`1`在位置`k`。 移动那个`1`进入专栏`j`，我们可以向左或向右旋转。 成本是：```
min((j - k) mod m, (k - j) mod m)
```对于每一行和每个目标列，我们可以扫描包含以下内容的所有位置`1`并采取最小的成本。 

这是可行的，因为一旦目标列固定，每行都是独立的。 

问题在于复杂性。 在最坏的情况下，每一行都包含`m`那些。 然后对于每个`m`我们扫描所有目标列`m`再次定位。 总复杂度变为：```
O(n * m^2)
```和`m = 10^4`，这达到了大约`10^10`原始操作，速度太慢。 

问题的结构提供了更好的选择。 对于固定行，我们想要每列到最近的距离`1`在一个圆圈上。 

这成为循环数组上的经典最近元素问题。 

有用的技巧是复制该行。 如果原始行有长度`m`，创建一个长度的概念数组`2m`重复两次。 现在圆形环绕变成普通的线性距离。 

我们从左到右扫描并跟踪最近的`1`在左侧。 然后我们从右向左扫描并跟踪最近的`1`在右侧。 组合这两个距离给出每列的最小循环距离。 

计算出一行对每一列的成本贡献后，我们将其添加到全局答案数组中。 

这将总复杂度降低到`O(n * m)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n * 平方米) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(n * m) | O(米) | 已接受 |

 ## 算法演练

 1.读取矩阵并创建数组`ans`尺寸的`m`，初始化为`0`。 
2. 独立处理每一行，因为一行的成本贡献不依赖于其他行。 
3. 如果某行不包含`1`，立即打印`-1`。 

没有循环移位可以创建`1`在该行中，因此不可能形成全一列。 
4. 通过将行与其自身连接来复制该行。 

这将循环运动转变为普通的线性运动。 靠近末端的位置现在可以自然地看到包裹的邻居。 
5. 创建数组`dist`长度`2m`，用一个大值初始化。 
6. 从左到右扫描。 

维持最新的位置`1`。 如果可以从该位置到达当前位置`1`，更新距离。 
7. 从右向左扫描。 

维护最近的`1`右侧并再次最小化距离。 
8. 对于每个原始列`j`，相关位置是`j`和`j + m`在双倍数组内。 

取这两个距离中的最小值。 这给出了距柱的真实循环距离`j`到最近的`1`。 
9.将该距离添加到`ans[j]`。 
10.处理完所有行后，打印最小值`ans`。 

### 为什么它有效

 对于固定目标列，最优策略对于每行都是独立的。 最小总成本是每行最小成本的总和。 

复制行会将圆形距离转换为线性距离。 两个位置之间的任何最短循环路径都显示为双倍数组内某处的普通段。 

两次扫描计算最近的`1`从左到右每个位置。 取最小值给出最短线性距离，这与复制后的最短循环移位距离相匹配。 

由于每一行都为每一列贡献了其确切的最小成本，并且我们最终选择了最便宜的列，因此该算法始终会产生全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    rows = [input().strip() for _ in range(n)]

    ans = [0] * m
    INF = 10**18

    for s in rows:
        if '1' not in s:
            print(-1)
            return

        t = s + s
        dist = [INF] * (2 * m)

        last = -INF

        for i in range(2 * m):
            if t[i] == '1':
                last = i
            dist[i] = min(dist[i], i - last)

        last = INF

        for i in range(2 * m - 1, -1, -1):
            if t[i] == '1':
                last = i
            dist[i] = min(dist[i], last - i)

        for j in range(m):
            ans[j] += min(dist[j], dist[j + m])

    print(min(ans))

solve()
```该解决方案维护每个目标列的运行总计。 每行独立地将其最小班次成本添加到总成本中。 

重复的字符串`t = s + s`是核心技巧。 如果没有重复，干净地处理环绕就会变得混乱且容易出错。 复制后，最近的`1`搜索的行为与普通的线性数组问题完全相同。 

从左到右扫描计算到最近的距离`1`在左侧。 从右到左扫描计算最近的`1`在右侧。 两者中的最小值就是真正的最短距离。 

表达式：```
min(dist[j], dist[j + m])
```很容易被忽视。 两个位置对应于相同的原始循环列。 两者都采用可确保正确包含环绕路径。 

使用非常大的哨兵，例如`10**18`避免扫描期间的特殊情况检查。

 ## 边缘情况

 考虑不可能的配置：```
2 4
0000
1010
```第一行不包含`1`。 在处理过程中，算法检查：```
if '1' not in s:
```并立即返回`-1`。 

这是正确的，因为循环移位仅重新排列现有值。 一行全零永远无法贡献`1`到任何列。 

现在考虑环绕行为：```
1 5
00001
```柱子`0`与现有的相比仅发生一处转变`1`。 

复制后：```
0000100001
```从左到右和从右到左扫描正确地检测到最近的`1`定位`0`是距离`1`， 不是`4`。 

这验证了循环变换技巧。 

最后，考虑最短路径穿过边界的情况：```
1 6
100000
```定位柱`5`应该花费`1`。 

在双倍字符串内部：```
100000100000
```位置`5`看到下一个`1`在位置`6`，给出距离`1`。 

幼稚的非循环实现会错误地返回`5`。
