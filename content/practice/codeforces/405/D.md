 ## 解决方案
 ## 问题理解

 我们得到了一个由从 1 到 1,000,000 编号的区块组成的大宇宙。 这些块的一些子集，称为$X$，已从克里斯的集合中删除。 从剩余的块中，我们需要选择一个非空子集$Y$从而满足非常具体的加权平衡条件。 

每个块对等式两侧的贡献不同。 对于每个移除的块$x \in X$，我们积累了贡献$x - 1$。 对于每个选定的块$y \in Y$，我们积累了贡献$1{,}000{,}000 - y$。 任务是构建任何有效的$Y$使得这两个总数相等，并且$Y$不得相交$X$。 

关键的难点在于$Y$不是任意的：它必须从补集中选择$X$，并且它必须匹配完全源自的固定目标总和$X$。 

制约因素很大。 宇宙的大小是$10^6$，以及禁止集$X$最多可包含$5 \cdot 10^5$元素。 这排除了任何尝试搜索子集或对整个总和范围执行动态编程的方法。 甚至$O(n \log n)$超过百万级域的构造必须小心处理，任何二次方都是不可能的。 

一些失败案例有助于阐明可能出现的问题。 

如果$X$为空，则目标和为零，因为左侧没有项。 粗心的方法可能会尝试选择其中的任何元素$Y$，但这会立即打破平等，因为每个有效$y$除非我们选择，否则在右侧贡献一个非负值$y = 1{,}000{,}000$，其贡献为零。 

如果$X$包含许多大数，例如$999999, 1000000$，目标总和变得非常大。 天真的贪婪，只考虑较小的值$y$会因为小而失败$y$做出巨大贡献$1{,}000{,}000 - y$，并且施工必须仔细平衡这些重量。 

另一个微妙的情况是当$X$在一个区域中是密集的，只留下稀疏的可用元素$Y$。 朴素的子集构造可能会假设连续性，但我们必须严格遵守禁止索引。 

## 方法

 蛮力策略将尝试建立$Y$通过检查可用元素的所有子集并计算它们的加权和，直到找到匹配项。 甚至限制我们自己的补充$X$, 最多有$10^6$元素，所以子集的数量为$2^{10^6}$，这是完全不可行的。 

更结构化的暴力可能会尝试对总和值进行动态编程，处理每个可用元素$y$作为有重量的物品$1{,}000{,}000 - y$。 这仍然失败，因为总和可能约为$10^{11}$，并且对于任何背包式解决方案来说，物品数量太大。 

关键的观察是可用的权重不是任意的。 对于每个允许的$y$，重量正好是$1{,}000{,}000 - y$，形成严格递减序列为$y$增加。 这意味着，如果我们按权重降序扫描候选者，我们可以贪婪地决定是否采用每个元素，同时保持剩余的所需总和。 

我们计算目标总和$T = \sum_{x \in X} (x - 1)$。 然后我们构建$Y$通过迭代所有数字$1{,}000{,}000$下降到$1$，并且每当数字不在$X$，我们考虑将其纳入$Y$。 如果它的贡献符合剩余目标，我们就会接受它。 

这是有效的，因为我们在单调权重序列上有效地执行贪婪子集构造。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力子集搜索 |$O(2^{10^6})$|$O(10^6)$| 太慢了 |
 | 贪心于递减的值 |$O(10^6)$|$O(10^6)$| 已接受 |

 ## 算法演练

 我们对待会员资格$X$作为快速查找结构，因此我们可以在恒定时间内测试可用性。 

1. 计算目标总和$T = \sum_{x \in X} (x - 1)$。 这个值是固定的，完全决定了我们必须在右侧构建什么。 
2. 存储所有元素$X$在布尔数组或哈希集中进行快速成员资格检查。 
3.初始化一个空列表$Y$并保留一个变量`remaining = T`。 
4. 迭代$i$从$1{,}000{,}000$下降到$1$。 
5. 如果$i$是在$X$，跳过它，因为它不能用于$Y$。 
6. 否则计算其贡献$w = 1{,}000{,}000 - i$。 如果$w \leq \text{remaining}$， 包括$i$在$Y$并减去$w$从`remaining`。 
7. 如果出现以下情况，请尽早停止`remaining`变为零，因为条件已经满足。 

第 6 步背后的原因是我们总是尝试首先消耗尽可能大的重量。 由于重量随着$i$增加，这种贪婪的选择确保我们不会为以后留下巨大的不可避免的差距。 

### 为什么它有效

 该过程维护一个必须使用可用权重形成的运行目标总和$1{,}000{,}000 - y$。 因为这些权重是按降序处理的，并且每个步骤要么完全采用或完全跳过一个项目，所以剩余值始终表示仍然可以使用更小或相等的权重形成的总和。 这种单调结构可以防止我们后悔之前的选择，因为任何跳过的较大权重只能由较小权重的组合来替换，并且在可能的情况下，该结构总是首先选择较大的权重。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

S = 10**6

n = int(input())
xs = list(map(int, input().split()))

in_x = [False] * (S + 1)
for x in xs:
    in_x[x] = True

target = 0
for x in xs:
    target += (x - 1)

y = []

for i in range(S, 0, -1):
    if in_x[i]:
        continue
    w = S - i
    if w <= target:
        y.append(i)
        target -= w
    if target == 0:
        break

print(len(y))
print(*y)
```解决方案首先对禁止集进行编码$X$在布尔数组中，因此成员资格检查是恒定时间。 目标总和是直接根据定义计算的。 

主循环从$10^6$因为较大的指数对应较小的贡献，这对于贪婪论证至关重要。 如果每个候选者属于$X$，或考虑纳入$Y$。 减法步骤强制我们永远不会超过所需的总和。 

当目标变为零时提前打破是安全的，因为额外的元素只会增加非负贡献，并且我们已经满足了等式。

 ## 边缘情况

 当$X$仅包含值$1{,}000{,}000$，目标总和是$999999$。 该算法会跳过该索引并立即开始从附近的索引进行累积。 由于每个候选者都贡献一个小的正权重，因此贪婪的人无需任何特殊处理即可填充目标。 

什么时候$X$是整个前缀$[1, 2, \dots, k]$，目标变成一个大的三角形数。 扫描仍然有效，因为所有所需的贡献都来自不禁止值的后缀，贪婪的人自然会积累足够的权重。 

什么时候$X$只留下一个非常小的补集，该算法只是迭代整个范围并在需要时选择每个可用元素。 正确性并不依赖于有很多选择，只依赖于使用剩余权重累积精确总和的能力。
