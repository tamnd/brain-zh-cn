 ## 解决方案
 ## 问题理解

 我们给出了一系列车轮压力，我们需要准确选择$m$其中。 选择那些之后$m$轮子上，我们可以改变它们的压力，使它们最终都等于一个值。 每个单位变化，即增加或减少 1 个轮子，需要 1 分钟。 

有一个额外的限制使问题不对称：虽然始终允许降低压力，但所有操作中增加的单元总数不能超过$k$。 因此，如果我们将轮子整体增加 5 个，则已经消耗了 5 个单位的全局增加预算。 

任务是选择哪个$m$要使用的轮子以及最终要达到的同等压力目标，以便最大限度地减少所花费的总时间，同时永远不会超过全局增加预算。 

种种限制迫使我们思考$O(n \log n)$或者$O(n)$条款。 和$n \le 2 \cdot 10^5$，任何尝试所有子集或所有子集对的解决方案都是立即不可能的。 甚至$O(n^2)$施工进度太慢。 这推动我们走向排序结构和基于连续段、前缀和或滑动窗口的解决方案。 

当一个人试图独立地确定目标值并贪婪地选择最接近的元素时，就会出现一种微妙的失败情况。 这忽略了将所有选定元素结合在一起的增加预算。 另一个陷阱是假设对称：成本不对称，因为增加受到全局限制，而减少总是允许不受限制。 

贪婪的每个元素选择失败的一个具体例子是，当高值略少但减少成本昂贵时，而低值很多但单独便宜，但它们的组合增加违反$k$。 天真的“选择最接近目标的”策略很容易在不经意间超出增加的预算。 

## 方法

 直接的蛮力想法是尝试所有大小子集$m$，并为每个子集尝试所有可能的最终相等值。 对于固定子集和目标值，我们可以通过对绝对差求和并跟踪总增量来计算成本。 这是正确的，但完全不可行：子集的数量是$\binom{n}{m}$，这是指数关系$n$，甚至评估每个子集也将是线性的$m$。 

关键的结构观察是，在对数组进行排序后，任何最佳的一组$m$轮子将按排序顺序形成一个连续的块。 原因是，如果我们固定最终值，则按排序顺序将较远的元素与较近的元素交换只能降低成本，而不会恶化增加的要求。 

一旦我们将自己限制在连续的长度段上$m$，问题变得更加结构化。 对于每个段，我们仍然需要确定最终的等值。 对于绝对偏差成本，最佳值始终是所选段的中值。 这大大减少了目标的选择。 

剩下的任务是检查每个大小的窗口$m$，在增加约束下是否可行并有效地计算其成本。 这可以使用排序数组上的前缀和来完成，从而允许每个窗口进行恒定时间评估。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集 |$O(\binom{n}{m} \cdot m)$|$O(m)$| 太慢了 |
 | 排序+滑动窗口+前缀和 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们首先对数组进行排序，以便任何候选组$m$轮子被表示为一个连续的段。 

然后我们检查每一段长度$m$，将其视为潜在的候选群体。 

1. 对数组进行排序$a$按非递减顺序。 
2. 构建前缀和，以便可以查询任何范围和$O(1)$。 
3. 对于每个窗口$[l, r]$长度$m$，计算中位位置$p = l + \frac{m-1}{2}$。 我们选择它作为最终的等压值。 
4. 计算将窗口左半部分中的所有元素提高到$a[p]$。 这是总的增加成本：$$\text{inc} = a[p] \cdot (p - l) - \sum_{i=l}^{p-1} a[i]$$如果这超过$k$，该窗口无效，我们跳过它。 
5. 计算使所有元素等于的全部成本$a[p]$：

 左侧贡献如上增加，右侧贡献减少：$$\text{dec} = \sum_{i=p+1}^{r} a[i] - a[p] \cdot (r - p)$$总成本为$\text{inc} + \text{dec}$。 
6. 跟踪所有有效窗口的最低成本。 

关键的决定是选择中位数作为目标值。 这对于最小化固定组内的绝对偏差是最佳的。 唯一的额外限制是确保不超过增加的预算，这仅取决于低于中位数的元素。 

### 为什么它有效

 对于任何选定的窗口，如果我们固定最终值，则最小化绝对偏差的最佳值就是中位数。 任何与中位数的偏差都会对称地增加两侧的总成本。 由于成本的增加仅取决于低于目标的要素，因此将目标偏离中位数要么会增加成本，要么会降低可行性，而不会改善总体目标。 因此，检查每个连续块的中值足以捕获所有最佳解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    INF = 10**30
    ans = INF

    for l in range(0, n - m + 1):
        r = l + m - 1
        p = l + (m - 1) // 2
        x = a[p]

        left_cnt = p - l
        left_sum = pref[p] - pref[l]
        inc = x * left_cnt - left_sum

        if inc > k:
            continue

        right_cnt = r - p
        right_sum = pref[r + 1] - pref[p + 1]
        dec = right_sum - x * right_cnt

        ans = min(ans, inc + dec)

    print(ans)

if __name__ == "__main__":
    solve()
```排序步骤确保每个最佳选择都按此顺序成为连续的窗口。 前缀和允许快速计算段和，这是至关重要的，因为重新计算每个窗口的和会导致$O(nm)$解决方案。 

唯一微妙的实现细节是围绕中位数的正确索引。 左侧严格在中值索引之前，右侧严格在中值索引之后开始。 混合包容性边界会错误地转移成本。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf

    def solve():
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        pref = [0] * (n + 1)
        for i in range(n):

        for l in range(n - m + 1):
            r = l + m - 1

        return str(ans)

 ## 边缘情况

 一种边缘情况是所有元素都相同。 在这种情况下，每个窗口的成本为零，并且算法不得由于计算的增加成本为零而错误地拒绝任何段。 该公式对于增加项和减少项都正确地生成零，因此每个窗口都是有效的。 

另一种边缘情况发生在$m = 1$。 中值逻辑仍然选择每个窗口中唯一的元素，并且增加和减少都变为零，与不需要改变的事实相匹配。 

一个更微妙的情况是$k = 0$。 此处，除非所有选定元素都已等于或高于中位数，否则任何元素低于中位数的窗口都将无效。 该算法可以正确处理此问题，因为在接受窗口之前，计算出的增加成本会严格检查为零。
