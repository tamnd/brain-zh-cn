 ## 解决方案
 ## 问题理解

 我们得到一个由几个隐藏整数序列生成的展平序列。 编码过程按“列顺序”将所有序列混合在一起：首先是每个序列的所有第一个元素，然后是所有第二个元素，然后是所有第三个元素，依此类推。 如果序列用完元素，则从该点开始，将使用特殊标记值 -1 来代替它。 

任务是从这个合并的流中重建原始序列，包括它们的分组和内部顺序。 

思考该过程的一种有用方法是，每个原始序列在每“轮”中贡献一个值。 在第 1 轮中，我们获取每个序列的第一个元素，在第 2 轮中，我们获取每个序列的第二个元素，依此类推。 仅当每个序列都贡献了其终止-1 时，编码才会停止。 

输出必须准确重建编码前存在的序列数量以及每个序列包含的内容。 

该约束允许最多 300,000 个编码值。 这立即排除了任何尝试以简单的嵌套方式重复扫描或模拟每个序列或每轮流程的解决方案。 我们需要一个线性重建来处理每个编码元素一次或恒定次数。 

一个微妙的困难来自于区分编码过程中的真实 -1 标记和结构终止。 每个序列恰好贡献一个 -1，并且这些 -1 值出现在同步的“轮次”中。 将 -1 视为所有序列的硬停止的简单方法会失败，因为序列在不同时间结束。 

另一个边缘情况是空序列。 有些序列可能根本不包含任何元素，这意味着它们的第一个贡献已经是-1。 这些仍然必须在输出中正确表示。 

## 方法

 暴力解释将尝试通过重复扫描序列、逐轮收集元素并将它们分配给序列直到出现终止标记来尝试反向模拟编码。 人们可以想象对编码数组进行多次迭代，每次都为仍然处于活动状态的所有序列提取下一个“列”值。 

这很快就会变得太慢。 如果有$m$元素和潜在的$O(m)$轮，每轮扫描一个大的前缀会导致$O(m^2)$最坏情况下的行为。 

关键的结构见解是编码保留了严格的交错模式：元素分层写入，并且在每一层中它们始终按序列顺序出现。 这意味着我们可以通过维护当前的活动序列列表并以流方式将每个遇到的值分配给正确的序列位置来增量重建序列。 

我们不考虑轮次，而是从左到右处理流并维护当前“活动”的序列的动态列表。 每次遇到一个值时，我们都会根据其在当前回合中的位置将其附加到正确的序列中。 当我们为某个序列点击 -1 时，该序列将从以后的回合中删除。 

主要挑战是当序列消失时跟踪每个值属于哪个序列。 该结构确保在每一轮中，我们始终按顺序填充序列，因此我们可以重用前几轮的位置并压缩活动集。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 逐轮暴力模拟 | O(平方米) | O(米) | 太慢了 |
 | 通过主动跟踪进行流式重建 | O(米) | O(米) | 已接受 |

 ## 算法演练

 1. 扫描编码序列并首先识别序列终止位置。 每个 -1 恰好对应一个序列的结尾。 由于序列每轮按顺序处理，因此序列最后一次出现在 -1 之前会告诉我们它的长度结构。 
2.维护当前正在重建的序列的动态列表。 最初，不创建任何序列。 
3. 迭代编码数组，同时将指针保持在当前“循环位置”。 对于每个值，决定是开始一个新序列还是继续现有序列。 
4. 当出现非-1值并且当前回合位置没有足够的活动序列时，创建一个新序列并将该值附加到它。 这反映了新序列在该位置贡献其第一个元素的事实。 
5. 当出现非-1 值并且该位置存在相应的活动序列时，将该值附加到该序列。 
6. 当遇到-1时，对应当前回合中在此位置结束的序列。 我们将该序列标记为已完成，并将其从主动跟踪中删除，以便它不再参与后续轮次。 
7. 继续，直到消耗掉整个编码数组，确保所有序列均已完全构建。 

关键的不变量是，在任何时刻，活动序列列表都准确地表示在当前或未来的轮次中仍然有元素可贡献的序列。 一轮中的每个位置对应一个稳定的序列身份，一旦通过-1删除序列，它就不会在以后的轮次中重新出现。 这保证了每个值都被精确地分配给正确的原始序列一次，从而保留了顺序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    m = int(input())
    b = list(map(int, input().split()))

    seqs = []
    active = []

    idx = 0

    for val in b:
        if val == -1:
            if idx < len(active):
                # mark sequence as finished
                active[idx] = None
            idx += 1
        else:
            if idx == len(active):
                active.append(len(seqs))
                seqs.append([])
            seq_id = active[idx]
            seqs[seq_id].append(val)

    # filter out removed slots if any
    result = []
    for i in active:
        if i is not None:
            result.append(seqs[i])

    print(len(result))
    for s in result:
        print(len(s), *s)

if __name__ == "__main__":
    solve()
```该代码维护两个结构：`seqs`，它存储重建的序列，并且`active`，它将当前回合位置映射到序列索引。 指针`idx`跟踪我们当前正在填充的列（圆形位置）。 当新值到达并且该位置不存在序列时，将创建一个新序列。 

一个`-1`标记当前占据该列的序列的终止，因此我们将其无效`active`。 这确保了后面的轮次不会再次追加到其中。 

最后的过滤步骤会删除提前结束的序列，并确保仅打印有效的重建序列。

 ## 边缘情况

 所有值均为 -1 的完全空场景表明该算法仍必须生成多个空序列，因为每个 -1 对应于不同序列的终止。 

例如：```
-1 -1 -1
```该算法为每个 -1 增加活动列指针，并将序列槽标记为终止。 即使没有附加实际值，仍然会重建三个序列。 

另一种边缘情况是序列在不同深度处结束。 在：```
1 2 -1 3 4
```第一个序列提前结束，而第二个序列继续增长。 该算法在删除第一个序列后正确地保持第二个序列处于活动状态，确保值不会错误地附加到终止序列。
