 ## 解决方案
 ## 问题理解

 我们得到了每日网站访问次数的序列。 每个位置代表一天，该位置的值代表当天发生的访问次数。 我们需要每天检查并判断是否“不好”。 

如果仅查看前几天的情况，如果一天中至少有两天的访问次数严格大于当天的值，则这一天会变得很糟糕。 早期的日子并不需要相邻，重要的是它们的价值观。 

任务是计算有多少个索引满足这个条件。 

天数限制最多为200,000。 这立即排除了任何在嵌套循环中将每一天与前一天进行比较的解决方案，因为这需要 n² 比较的顺序，这对于 3 秒的限制来说太大了。 线性或近线性扫描是必要的，可能每个元素需要少量固定的额外工作。 

天真的推理的一个微妙的失败案例来自于忘记我们只关心有多少先前的值更大，而不是它们的位置。 例如，在像 [10, 1, 9, 8] 这样的序列中，第二个元素在它之前看到两个较大的值，而后面​​的元素可能具有更少的值，即使数组不是单调的。 另一个边缘情况是重复值。 由于条件严格大于，因此不得计算相等的值。 

## 方法

 直接方法每天独立检查。 对于固定索引 i，我们扫描所有 j < i 并计算有多少个 a[j] > a[i]。 如果该计数至少为两次，我们将这一天标记为糟糕的一天。 这是正确的，因为它完全遵循定义。 然而，每个位置可能需要扫描最多 i-1 个元素，并且在所有 i 中，这大约是 n(n-1)/2 次比较。 当 n = 200,000 时，这是不可行的。 

关键的观察是，对于每一天，我们只关心它之前是否至少有两个更大的值。 这是一个阈值条件，而不是超过二的精确计数。 这意味着我们不需要有关所有先前元素的完整信息，只需要是否可以识别前几天迄今为止看到的两个最大值。 

一旦我们意识到这一点，结构就变得简单了。 当我们从左到右迭代时，我们维护迄今为止遇到的最大和第二大值。 对于每个新的一天，我们将其值与这两个跟踪的最大值进行比较。 如果两个存储的最大值都严格大于当前值，则必须至少有两天之前超过它，所以这是不好的。 

这是有效的，因为任何大于当前值的元素都必须位于迄今为止看到的全局最高值中。 如果至少有两个这样的元素，它们必然占据前缀中的第一和第二最大位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了 |
 | 保持两个最大值| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.初始化两个变量，`first`和`second`，跟踪迄今为止看到的最大和第二大值。 我们将它们设置为负无穷大，以便任何输入值都能正确替换它们。 
2. 初始化计数器`bad = 0`累积糟糕的日子数。 
3. 从左到右迭代数组。 
4. 对于当前值`x`，检查两者是否`first > x`和`second > x`抓住。 如果确实如此，那么至少前两天的值严格更大，因此我们增加`bad`。 
5. 处理完条件后，将跟踪的最大值更新为`x`。 如果`x >= first`， 转移`first`进入`second`并分配`first = x`。 否则，如果`x >= second`， 更新`second = x`。 

更新的顺序很重要，因为我们必须仅使用先前的元素来评估条件。 Updating after checking ensures the current day is not counted among its own history.

 ### 为什么它有效

 在每一个位置上，`first`和`second`存储所有先前索引的最大和第二最大值。 因此，条件`first > x and second > x`相当于说至少有两个较早的元素超过`x`。 任何其他值都不能违反此等价性，因为任何大于`x`必须在前缀最大值之间，并且如果至少有两个这样的值，则它们必须占用这两个跟踪时隙。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    first = float("-inf")
    second = float("-inf")
    
    bad = 0
    
    for x in a:
        if first > x and second > x:
            bad += 1
        
        if x >= first:
            second = first
            first = x
        elif x >= second:
            second = x
    
    print(bad)

if __name__ == "__main__":
    solve()
```该解决方案一次性处理数组。 条件检查仅使用存储在的前缀信息`first`和`second`，保证正确性。 更新步骤会仔细维护顺序，以便正确处理关系：使用`>=`确保以某种方式跟踪重复项，从而保留在后续步骤中正确计算严格较大比较的能力。

 ## 边缘情况

 一种边缘情况是数组严格递减，例如 [9, 7, 5, 3, 1]。 算法更新`first`和`second`这样在前两个元素之后，两者都很大。 从第三个元素开始，每个新值都小于两个存储的最大值，因此每个后续位置都被视为错误。 这与定义匹配，因为每个这样的元素至少有两个较早的较大值。 

另一个边缘情况是重复值，例如 [5, 5, 5, 5]。 在这里，尽管有许多较早的元素，但没有一个元素严格大于任何给定元素。 条件`first > x and second > x`永远不会成为现实，因为`first`和`second`一旦平等占主导地位，就永远不会严格大于当前值。 这正确地产生了零糟糕的日子。
