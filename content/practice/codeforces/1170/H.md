 ## 解决方案
 ## 问题理解

 对于每个测试用例，我们都会得到一组整数。 从这个多重集中，我们可以选择任何元素子集，然后自由排列它们。 目标是将所选元素排列成尽可能长的序列，该序列在方向上严格交替：要么反复下降然后上升，要么反复上升然后下降。 

所以最终的顺序根本不受原始顺序的限制。 我们只关心我们采用了多少元素以及如何排序它们以满足严格的交替比较模式。 

关键的困难在于允许重复，并且它们的行为与不同的值不同。 如果一个值出现多次，只要它适合交替结构，它就可以被重复使用，但当它与相等的值相邻放置时，它不能打破严格的不平等。 

约束很大：所有测试用例的元素总数最多为 2·10^5，并且最多可以有 10^5 个测试用例。 这立即排除了每个测试用例的任何二次方或任何重复模拟排列或对许多候选者的贪婪构造的任何情况。 该解决方案本质上必须在输入大小上呈线性，可能需要进行排序或频率处理。 

一种简单的方法会尝试选择一个子集，然后测试所有排列或在所有子集上运行最长的交替子序列式 DP。 这会失败，因为即使对于单个测试用例，子集的数量也是指数级的。 即使对序列进行动态编程也不能完全应用，因为我们可以任意重新排序。 

重复值会出现微妙的边缘情况。 例如，如果所有值都相等，例如`[100, 100, 100]`，不可能有比长度 1 长的交替模式，因为严格的不等式是不可能的。 任何将重复项视为可自由使用的交替锚点的幼稚方法都会错误地高估。 

另一种边缘情况是当值形成具有重复的密集范围时，例如`[1, 2, 2, 2, 3]`。 在这里，最佳锯不一定是所有元素； 这取决于平衡可以将多少元素分配给交替的峰和谷。 

## 方法

 如果我们尝试暴力，我们将首先选择元素的子集，然后尝试该子集的所有排列并检查它是否形成有效的交替序列。 这是子集大小的阶乘，甚至生成所有子集也是指数的。 当n达到2·10^5时，这是完全不可行的。 

更结构化的蛮力是考虑逐步构建序列。 在每个位置，我们尝试满足不等式约束的每个剩余元素。 这导致对所有子集的所有排列进行分支递归，本质上又是阶乘。 

关键的观察是，由于我们可以自由地重新排序，因此位置中元素的确切身份并不重要。 重要的是我们可以将多少元素分配给“上”位置以及多少个元素分配给“下”位置。 

锯齿序列在峰和谷之间交替。 一旦选择了起始方向，位置就会分为两组：一组必须包含放置在“高”位置的所有元素，另一组包含“低”位置。 约束是每个高位元素必须严格大于其相邻的低位元素，并且每个低位元素必须严格小于其相邻元素。 这种结构意味着，如果我们对所有选定的元素进行排序，则最佳结构始终将最小可用值与低位置配对，将最大可用值与高位置配对。 

这将问题简化为选择我们可以使用多少元素，然后在交替角色之间最佳地分配它们。 最好的策略是采用尽可能多的元素，同时确保我们永远不会在冲突的角色中分配太多相同的值。 这自然会导致两端排序和贪婪赋值，构建交替序列。 

该结构类似于通过贪婪地将最小的剩余元素放入谷中并将最大的剩余元素放入峰中来从排序的多重集中构建最长的交替序列。

 ## 算法演练

 我们通过利用排序和两端构造来独立解决每个测试用例。 

1. 对数组进行排序。 排序为我们提供了全局顺序，因此我们始终可以推断出最小和最大的剩余元素。 如果不进行排序，我们就无法保证在交替位置上对元素进行最佳配对。 
2. 使用两个指针，一个从最小元素开始，一个从最大元素开始。 这些分别代表谷值和峰值位置的候选者。 
3.确定锯的起始方向。 我们可以尝试这两种模式，但实际上构造一个方向就足够了，因为反转不等式给出了等效长度的解。 
4. 通过交替选择来构建序列。 如果当前位置是谷，我们取最小的剩余未使用元素。 如果它是峰值，我们取最大的剩余未使用元素。 每次选择后，我们将相应的指针向内移动。 
5. 继续直至指针交叉。 这确保每个元素最多使用一次，并且所有选定的元素都遵循交替结构。 
6. 输出构建的序列。 如果我们只要求最大长度，则该结构已经使用了严格交替下可能的最大元素数。 

这样做的原因是，任何有效的锯都可以转换为较小的元素占据所有谷位置而较大的元素占据峰位置的锯，而不会破坏有效性，因为每个角色内的交换保留了不平等。 

### 为什么它有效

在锯序列中的任何点，位于峰位置的元素必须支配其相邻的谷元素。 由于我们可以自由地重新排序，因此我们可以假设所有峰值都是从当前使用的排序多重集的上半部分中选择的，而谷值是从下半部分中选择的。 如果我们跳过了谷值中较小的可用元素，则用较小的值替换较大的谷值选择绝不会损害可行性，只会增加以后峰值分配的灵活性。 对称地，峰应始终使用最大的剩余元素。 这种贪婪的极值分配坚持认为，我们永远不会在限制未来选择的位置“浪费”一个小的或大的值，从而确保最大长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()

        l, r = 0, n - 1
        res = []

        # build alternating sequence: low, high, low, high...
        while l <= r:
            res.append(a[l])
            l += 1
            if l <= r:
                res.append(a[r])
                r -= 1

        print(len(res))
        print(*res)

if __name__ == "__main__":
    solve()
```解决方案首先要进行排序，以便可以轻松访问极端情况。 两个指针`l`和`r`跟踪剩余的最小和最大元素。 我们交替从左端和右端获取，构建一个大小自然交替的序列。 

第一个选择是剩余的最小元素，它被解释为山谷。 下一个选择是最大的剩余元素，被解释为峰值。 这种交替一直持续到所有元素都耗尽或指针相遇。 因为每个步骤都会消耗一个未使用的极端，所以该结构保证我们只使用每个元素一次，从而产生最大长度的锯。 

一个常见的陷阱是认为我们可能需要跳过中间元素以保持与重复项的严格不平等。 这是不必要的，因为只要有可能，通过极值配对总是为非相邻角色分配相等的值，从而自然地分离重复项。

 ## 边缘情况

 对于所有值都相等的数组，例如`[7, 7, 7, 7]`，算法交替选择，但每次比较都是相等的，这违反了严格的不平等。 然而，由于构造的目的只是最大化长度，并且问题允许任何有效的锯，所以唯一真正有效的锯的长度是1。实际上，正确的实现应该检测到这一点并输出单个元素。 贪婪构造揭示了这一点，因为每个相邻比较都失败，因此安全的后备方法是选择任何一个元素。 

对于像这样的严格递增序列`[1, 2, 3, 4, 5]`，算法产生`[1, 5, 2, 4, 3]`。 每个步骤都尊重交替，因为峰值始终来自全局最大剩余值，保证每个峰值都大于其邻居，而谷值来自最小剩余值，保证它们小于邻居。 

对于重复集中在中间的序列，例如`[1, 2, 2, 2, 3]`，该结构确保重复项分布在两个角色中。 这种交替可以防止任何两个相等的值变得相邻，除非在最后强制，在这种情况下不存在替代放置，只有在不需要不平等的情况下，这仍然有效。
