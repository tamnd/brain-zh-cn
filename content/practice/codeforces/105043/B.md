 ## 解决方案
 ## 问题理解

 我们得到了一系列沿直线排列的柱子高度。 每个位置都有一个高度，我们也有一个阈值`x`。 任务是找到这些柱子的连续部分，使得该部分内的每个柱子的高度最多`x`。 在所有这些有效段中，我们想要最大可能的长度。 

简单来说，想象一下沿着阵列行走并且只允许停留在高度不超过的位置`x`。 每当你撞到一根太高的柱子时，你必须停止该部分并在其后开始新的部分。 答案是最长的不间断的“允许”位置。 

输入大小可能非常大，最多 700,000 个元素。 这立即排除了任何显式检查所有子段的解决方案。 二次方法将涉及考虑所有起始位置并向右扩展，在最坏的情况下，其执行顺序为$n^2$检查，对于这个约束来说太慢了。 因此，该解决方案必须在线性时间内处理该数组。 

当所有元素都大于时，会出现微妙的边缘情况`x`。 在这种情况下，不存在有效段，答案为零。 另一个极端情况是当所有元素都有效时，在这种情况下答案很简单`n`。 

天真的错误通常来自于将问题视为全局“计数元素 ≤ x”，而不是尊重连续性。 例如，如果数组是`[1, 100, 2, 3]`和`x = 50`，有效元素为 1, 2, 3，但它们不构成一个线段。 正确答案是 2，而不是 3。 

## 方法

 蛮力的想法很简单：对于每个起始索引，在所有元素保持 ≤ x 的情况下向右扩展一个窗口，并计算其长度。 这正确地找到了所有有效段，但在最坏的情况下，所有元素都 ≤ x，每个起始索引扫描到末尾，大致产生$n + (n-1) + \dots + 1$运算，是二次的。 

关键的观察是，有效性仅取决于每个单独元素是否 ≤ x，并且段的条件纯粹是局部的。 我们不需要维护复杂的结构或跨段重新计算任何内容。 相反，数组自然地分割成“好”值的最大连续块。 每次我们遇到一个大于的元素`x`，它完全破坏了结构，将当前段长度重置为零。 

这将问题简化为单个线性扫描，其中我们跟踪当前有效运行的长度并维护所有运行的最大值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 单次扫描 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们从左到右处理数组，同时维护两个值：当前有效段的长度和迄今为止看到的最佳答案。 

1. 初始化`cur = 0`和`best = 0`。 变量`cur`跟踪当前有效元素的连续性，同时`best`存储迄今为止发现的最大条纹。 
2. 迭代数组中的每个高度。 对于每个元素，检查它是否≤x。 这决定了是否可以扩展当前的有效段。 
3. 如果元素 ≤ x，则递增`cur`加 1 是因为有效段继续不间断。 这反映了当前仓位延长了当前运行。 
4.如果元素大于x，则重置`cur`为 0。这是必要的，因为有效性条件要求段中的所有元素都满足约束，而该元素完全破坏了连续性。 
5.更新后`cur`， 更新`best = max(best, cur)`记录迄今为止看到的最长有效段。 
6.处理完整个数组后，输出`best`。 

### 为什么它有效

 在任何位置，`cur`精确表示当前连续后缀的长度，该后缀结束于所有值 ≤ x 的位置。 每次重置时，我们都会在无效元素处精确切割数组，这是有效段唯一可能的断点。 由于每个有效段必须完全位于两个无效元素（或边界）之间，因此每个候选段都被完全捕获为`cur`，确保没有遗漏有效段并且没有计算无效段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    cur = 0
    best = 0

    for v in a:
        if v <= x:
            cur += 1
            if cur > best:
                best = cur
        else:
            cur = 0

    print(best)

if __name__ == "__main__":
    solve()
```该实现一次性读取输入并仅维护恒定的额外状态。 关键细节是当遇到大于的值时立即发生重置`x`，确保没有无效元素污染段。 最大更新是在扩展当前运行后完成的，这确保了每次运行的最终值都被正确捕获。

 ## 边缘情况

 完全无效的数组，例如`5 3 / 10 11 12 13 14`演示了复位机制的反复触发。 该算法永远不会递增`cur`，所以它始终保持为零，并且`best`保持为零，正确捕获不存在有效段。 

一个完全有效的数组，例如`5 10 / 1 2 3 4 5`永远不会触发重置。 变量`cur`累积到`n`， 和`best`每一步都会更新，结束于`5`。 这表明该算法不需要显式检测段边界，因为连续性自然是通过累积来处理的。 

混合情况如`6 4 / 1 2 10 3 4 5`显示将数组分成两个候选段的单个中断`[1,2]`和`[3,4,5]`。 该算法通过独立运行正确评估两者`cur`， 和`best`捕获其中的最大值，即`3`。
