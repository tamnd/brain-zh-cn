 ## 解决方案
 先前的解决方案是基于对问题的误解。 

目标不是**精确匹配示例输出。 示例输出显示了众多答案中的一个有效答案。 真正的要求是：

 1.`t`必须是一个子序列`s`。 
2.`|s| ≤ 2|t|`。 
3.`s`必须具有尽可能最小的周期。 

我们来分析一下失败的案例。 

对于输入：```
00
```之前的解决方案输出：```
0000
```样本显示：```
00
```两者都有效。 实际上，`"0000"`周期为 1，`"00"`周期为 1，并且`"00"`是一个子序列`"0000"`。 这里没有与该问题相关的错误。 

对于输入：```
110
```之前的解决方案输出：```
101010
```样本显示：```
1010
```同样，两者都是有效的。`"110"`是一个子序列`"101010"`还有的`"1010"`。 两个字符串都有周期 2，这是两个数字出现后可能出现的最小值。 

所以问题不在于算法违反了问题。 问题在于，它显然是根据确切的示例输出进行检查的，而 Codeforces **不需要** 需要这一点。 

也就是说，早期的建设时间比必要的要长。 标准接受的解决方案要简单得多：

 - 如果`t`完全由`0`或全部`1`s，输出`t`本身。 可能的最小周期为 1。 
- 否则，输出长度交替的字符串`2 * len(t)`:

 -`"010101..."`如果两个数字都出现。 
- 这总是包含`t`作为一个子序列，周期为 2，这是当两者都存在时可能的最小值`0`和`1`存在。 

这是 Codeforces 1342B 公认的规范解决方案。```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())

    for _ in range(T):
        t = input().strip()

        if all(c == t[0] for c in t):
            print(t)
        else:
            print("01" * len(t))

solve()
```为什么这有效：

 - 如果所有字符都相同，则可以实现周期 1，并且任何字符串都不能具有更小的正周期。 
- 如果两者都`0`和`1`如果发生这种情况，周期 1 是不可能的，因为周期 1 的二进制字符串仅包含一个不同的字符。 
- 因此，最小可能周期为 2。 
- 交替字符串`"0101..."`有周期 2。 
- 任何二进制字符串都可以作为足够长的交替字符串的子序列嵌入。 使用长度`2|t|`就足够了并且满足问题的长度限制。 

该解决方案是标准接受的 Codeforces 解决方案，运行于`O(|t|)`每个测试用例。
