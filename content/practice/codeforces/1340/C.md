 ## 解决方案
 ## 问题理解

 我们给出一条笔直的道路，建模为从 0 到 n 的整数点。 其中一些点是称为安全岛的特殊位置，包括两个端点。 Denis 从时间 0 的 0 开始，希望尽快达到 n。 

时间由重复的交通灯周期控制。 它保持绿色 g 秒，然后红色 r 秒，并重复。 只能在绿色秒内移动，并且每一秒的移动都会向左或向右精确改变一个单位。 

还有一个额外的结构限制从根本上影响了运动：丹尼斯只有在安全岛上时才能反转方向。 在岛屿之外，一旦他开始朝某个方向移动，他就被迫继续朝该方向移动，直到到达岛屿。 这会将道路变成一个约束图，其中仅允许在特定节点处改变方向。 

第二个限制与交通灯有关：在红灯时段，丹尼斯必须站在安全岛上。 当红色开始或红色激活时，他不允许“过境”。 

任务是计算达到 n 所需的最短时间，或者确定这是不可能的。 

这些约束意味着 n 可以大到 10^6，而岛屿的数量 m 最多为 10^4。 这立即排除了任何明确模拟每个道路位置的方法。 任何解决方案都必须将问题压缩到仅重要的位置，即岛屿，并推理它们之间的运动。 

当贪婪地思考在绿灯时间总是向前移动时，就会出现一个微妙的失败案例。 考虑这样一种情况：到达下一个岛屿需要多个绿色部分，但移动不能在中间边缘暂停，除非存在岛屿。 一个简单的“只要绿色就移动”的简单模拟在这里中断，因为当红色开始时它可能最终进入边缘内部。 

另一个常见的陷阱是忽略方向限制。 例如，即使从两边都可以到达一个岛屿，除非你正好在那个岛上，否则你不能自由掉头。 假设没有状态的岛屿之间无定向移动的最短路径方法将会过多计算不可能的转变。 

最后，时序调整很重要。 即使两个岛屿很接近，在绿色阶段结束时开始遍历也可能会迫使等待，而这种等待会与未来的周期相互作用。 

## 方法

 蛮力的想法是每秒模拟整个过程。 在每个时间步，我们都会跟踪丹尼斯的位置、方向以及他当前是否受到移动规则的限制。 在每个州，如果允许，我们都会尝试向左或向右移动，并强制执行交通灯限制。 这是正确的，但立即不可行：位置会增加到 10^6 并且时间也会变长，因此状态空间会爆炸到 O(n · (g + r) · 2) 之类的东西，并且每秒都会发生转换。 

关键的观察结果是，只有岛屿才是重要的决策点。 在岛屿之间，移动是确定的：一旦选择了方向，丹尼斯就会沿直线移动。 唯一的复杂性是这种穿越是否可以在红绿灯周期内合法地安排，而不违反非岛红灯规则。 

这将问题转换为简化图上的最短路径问题，其中节点是岛。 困难在于边缘不是静态成本；而是静态成本。 它们取决于当前时间模 (g + r)。 因此，我们必须在状态中包含时间阶段。

这导致了一个图表，其中每个状态都是通过位于一个岛上并了解交通灯周期内的当前时间来定义的。 在这种状态下，我们可以等待或尝试穿越到邻近的岛屿。 仅当移动可以完全安排在绿色段内且在红色期间永远不会离开岛屿时，遍历才有效。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对位置和时间的全面模拟 | O(n·(g+r)) | O(n·(g+r)) | O(n·(g+r)) | O(n·(g+r)) | 太慢了|
 | 具有时间模式状态的岛屿上的最短路径 | O(m·(g+r) log (m·(g+r))) | O(m·(g+r) log (m·(g+r))) | O(m·(g+r)) | 已接受 |

 ## 算法演练

 我们将道路压缩为仅排序的岛屿列表。 在此顺序中，只能在连续的岛屿之间进行移动，因为丹尼斯无法以允许改变方向的方式“跳过”非岛屿转折点。 

每个状态由一对岛索引和交通周期内的当前时间组成。 我们在这些状态上运行 Dijkstra，因为转换的成本取决于绿色阶段对齐之前的等待时间。 

1. 对岛屿坐标进行排序。 这定义了一个线性图，其中每个岛屿都与其直接相邻的岛屿相连。 该结构成为一条路径而不是完整的图。 
2. 定义流量周期长度为T = g + r。 每个状态都跟踪时间模 T，因为信号模式精确地重复每个周期。 
3. 从状态（位置0、时间0的岛屿）开始。 这始终有效，因为我们在绿灯亮起时从安全岛开始。 
4. 从任意状态 (i, t) 计算我们处于绿色还是红色。 如果t<g，则允许移动； 否则，我们处于红色状态，并且被迫等待，直到下一个周期在时间 T 开始。 
5. 如果我们处于红色，则唯一的转换是等待时间变为 T（将模数重置为 0）。 这强制执行了红色期间丹尼斯必须留在岛上的规则。 
6. 如果我们是绿色的，我们可以尝试移动到相邻的岛屿 i-1 和 i+1。 设到邻居的距离为d。 我们尝试模拟 Denis 是否可以从时间 t 开始穿越这段距离。 
7. 仅当丹尼斯在边缘中间从未撞到红色时，遍历才有效。 这意味着整个段必须适合可用的绿色窗口，可能跨越多个周期，但每个红色间隔必须与位于岛上的情况一致。 通过计算当前周期中可用的绿灯时间、尽可能远地移动并逐周期重复来强制执行此约束。 
8. 每次成功的遍历都会导致目的地岛屿出现新的状态，并更新时间模 T 和累积的总时间。 我们在 Dijkstra 中放松了这一优势。 
9. 答案是到达最后一个岛的所有状态中时间最短的。 

### 为什么它有效

 该算法将连续运动问题简化为仅在岛屿上进行转换，这是唯一允许方向改变的点。 任何有效的轨迹都可以分解为岛屿之间的分段以及与交通周期一致的岛屿等待时间。 通过跟踪以周期为模的时间，我们保留了足够的信息来确定未来走势的可行性，而无需完整的历史记录。 Dijkstra 确保我们始终按时间递增顺序扩展状态，因此我们第一次到达目的地的时间是最佳的。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    pos = list(map(int, input().split()))
    g, r = map(int, input().split())

    pos.sort()
    idx = {x: i for i, x in enumerate(pos)}

    T = g + r
    INF = 10**18

    # dist[i][t] = minimum time to reach island i at time mod T = t
    dist = [[INF] * T for _ in range(m)]
    dist[0][0] = 0

    pq = [(0, 0, 0)]  # time, island, time_mod

    while pq:
        time, i, tmod = heapq.heappop(pq)
        if time != dist[i][tmod]:
            continue

        if i == m - 1:
            print(time)
            return

        # if red light: wait until next cycle
        if tmod >= g:
            nt = time + (T - tmod)
            ntmod = 0
            if nt < dist[i][ntmod]:
                dist[i][ntmod] = nt
                heapq.heappush(pq, (nt, i, ntmod))
            continue

        # try moving to neighbors
        for ni in (i - 1, i + 1):
            if 0 <= ni < m:
                d = abs(pos[ni] - pos[i])

                # simulate movement during green cycles
                cur_time = time
                cur_mod = tmod
                rem = d

                ok = True

                while rem > 0:
                    if cur_mod >= g:
                        ok = False
                        break

                    can = min(rem, g - cur_mod)
                    rem -= can
                    cur_time += can
                    cur_mod += can

                    if rem == 0:
                        break

                    # hit end of green, must wait for next cycle
                    cur_time += (T - cur_mod)
                    cur_mod = 0

                if ok:
                    if cur_time < dist[ni][cur_mod]:
                        dist[ni][cur_mod] = cur_time
                        heapq.heappush(pq, (cur_time, ni, cur_mod))

solve()
```该代码结合交通周期内的当前位置对岛屿索引实施 Dijkstra 搜索。 关键的实现细节是运动模拟循环，它仅在绿色阶段消耗距离，并在运动完成之前每当绿色阶段结束时显式插入等待时间。 

一个常见的错误是在等待后忘记重置模数时间。 另一种尝试将运动视为等于距离的简单边缘权重，这忽略了运动的一部分可能被迫在红色周期暂停。

 ## 边缘情况

 当两个岛屿与绿灯持续时间相比相距较远时，就会出现关键的边缘情况。 尽管运动原则上是连续的，但红灯禁止在岛屿之间的限制会迫使失败，除非该段可以跨周期突破而无需在中间边缘停止。 

另一种情况是在红色开始时到达岛屿。 在那一刻，状态仍然有效，因为丹尼斯在岛上，但任何立即移动的尝试都会被阻止，直到下一个绿色阶段。 该算法通过在允许任何移动之前将状态推入等待转换来处理此问题。 

最后一个微妙的情况是，最佳策略涉及故意在岛屿之间摇摆。 从最短路径直觉来看，这并不明显，但很自然地可以处理，因为状态空间允许重新访问具有不同循环阶段的岛屿，并且 Dijkstra 确保循环在改进时序时被探索。
