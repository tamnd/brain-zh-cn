 ## 解决方案
 ## 问题理解

 我们得到了一个小排列，这意味着从 1 到 n 的每个数字都只出现一次。 任务是确定我们是否可以使用涉及三个索引 i < j < k 的非常具体的操作将该数组转换为排序顺序。 

每个操作以两种方式之一进行操作，具体取决于位置 i 和 k 处的值之间的比较。 如果 i 处的值大于 k 处的值，我们可以通过添加 a[j] 来增加 i 处的值。 否则，我们可以交换位置 j 和 k 的元素。 

目标不是模拟固定的排序算法，而是决定是否有可能通过重复使用此操作，最终达到排序排列。 

约束条件非常小，n 最多为 10，这表明暴力状态搜索乍一看似乎很诱人。 然而，操作的分支因子很大，因为指数的每个三元组都是潜在的变动，并且值可以改变，而不仅仅是位置。 即使在如此小的 n 中，完整状态上的朴素 BFS 也会变得混乱，因为在第一种类型的操作之后值不再是有界排列。 

一个关键的微妙边缘情况是第一个操作改变了值，破坏了排列结构。 例如，从有效排列开始，应用“加法”步骤可以产生大于 n 的值，如果我们尝试直接模拟，这会使状态跟踪变得更加困难。 

另一个重要的场景是当交换看似可用但实际上被 a[i] 和 a[k] 上的条件阻止时。 例如，如果最小元素的位置不正确，则即使语法上存在交换，也可能会阻止任何有用的重新排列。 

## 方法

 强力方法会将每个阵列配置视为一种状态并探索所有可能的操作。 从给定的状态，我们将尝试每个三元组 i < j < k，生成交换或值更改，并继续搜索，直到到达排序数组或耗尽可能性。 

这在原则上是正确的，因为它精确地模拟了规则。 然而，州的数量立即爆炸。 即使忽略增加带来的价值增长，也有n！ 排列，每个状态分支为 O(n^3) 个转换。 一旦值发生变化，状态空间就不再受到排列的限制，使得搜索从根本上不受控制。 

关键的观察结果是，该操作隐藏着非常强的结构约束。 仅当 a[i] ≤ a[k] 时才启用交换操作。 这个单一条件决定了我们是否可以对元素进行重新排序。 如果存在一个相对于所有其他值始终满足此条件的头寸，那么它就成为掉期的通用推动者。 

这引出了关键的见解：值 1 起着特殊的作用。 由于所有值都是正数且不同，因此每当 a[i] = 1 时，与 1 的任何比较都将满足 a[i] ≤ a[k]。如果我们可以将 1 定位在第一个索引处，它可以充当所有后续位置之间交换的永久促进器，从而有效地允许后缀的任意重新排列。 

一旦发生这种情况，排序就变得很简单，因为我们可以使用三元运算模拟数组中任何位置的相邻交换。 

因此，整个问题归结为检查我们是否在一开始就已经有了这个“支持交换的锚点”。

 ## 算法演练

 ###核心理念

 我们检查数组的第一个元素是否等于 1。 

### 步骤

1. 读取当前测试用例的数组。 
2. 检查位置 1 处的值（0-索引位置 0）。 
3. 如果等于1，则输出“Yes”。 
4. 否则，输出“No”。 

此检查背后的原因是，只有当 1 位于第一个位置时，它才能在每个三元组运算中用作固定辅助元素。 如果没有这个，交换操作就会受到涉及较大值的比较的限制，从而阻止完全重新排列。 

### 为什么它有效

 仅当左侧存在 i 使得 a[i] ≤ a[k] 时，该操作才允许交换 j 和 k。 如果第一个元素是 1，则选择 i = 1 可保证此条件对于任何 k 始终成立，因为 1 是最小的可能值。 这意味着任何对 (j, k) 都可以自由交换，因此可以将数组任意排列成排序顺序。 

如果 1 不在第一个位置，则无法使其充当交换的通用最小主元，并且对 i 的限制阻止我们自由地重新排序元素。 数组陷入无法保证完全排序的结构中。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        if a[0] == 1:
            print("Yes")
        else:
            print("No")

if __name__ == "__main__":
    solve()
```该解决方案独立读取每个测试用例，并对每个用例执行恒定时间检查。 唯一微妙的一点是索引：我们直接检查第一个元素，因为这是确定是否可以进行无限制交换的唯一位置。 

不需要模拟操作，因为决策完全减少到值 1 的位置。

 ## 边缘情况

 如果最小元素不在第一个位置，即使它存在于数组中的某个位置，它也不能充当全局交换启用器。 i 的条件要求 i < j < k，因此主元必须始终严格位于任何交换操作的左侧。 只有当 1 从索引 1 开始时，它才能始终充当所有其他对的枢轴。 

例如，在`[2,1,3,4,5]`，值 1 存在，但不能用作通用助手，因为它不适用于所有位置的左侧。 该算法正确地输出“否”，符合没有任何操作序列可以完全解锁任意重新排序的事实。
