 ## 问题理解

 在特殊编辑器中进行一系列键入操作后，我们会得到最后一个括号字符串，该字符串出现在屏幕上。 编辑器以字符串的两个部分之间的光标开始为空，并且在每一步用户都键入左括号或右括号。 键入的效果不是通常的“末尾追加”行为。 相反，光标将字符串分成左部分和右部分，并且每个键入的字符以受约束的方式与光标位置和现有的右部分交互。 

键入左括号始终会将其准确插入到光标位置，并将右侧部分向前推。 键入右括号的行为有所不同，具体取决于紧随光标之后的内容：如果右侧部分的下一个字符是右括号，则除了光标向右移动一步之外，键入的字符将被有效忽略。 否则，右括号将插入到光标处。 

任务是这个过程的逆过程。 我们得到了最终的字符串，并且必须确定是否存在一些可以在这些规则下产生它的键入括号序列。 如果是，我们输出任何有效的键入字符序列，并且该序列不需要与最终字符串相同。 它只需要代表可行的操作历史。 如果不存在这样的序列，我们必须输出它是不可能的。 

所有测试用例的总长度高达一百万，这迫使每个测试用例进行线性或近线性重建。 任何试图模拟所有可能的打字历史或决策分支的方法都会失败，因为如果处理得天真，即使是长度为 n 的单个字符串也可能会出现指数级的可能性。 

最微妙的边缘情况来自长串的右括号。 例如，像“))))”这样的字符串会强制光标行为重复依赖于是否存在匹配的右侧括号。 贪婪地假设每个字符都必须已显式键入的天真重建可能会错误地得出不可能性的结论或产生无效的键入序列，因为它忽略了某些右括号可能是由光标跳过而不是插入产生的。 

当括号完美平衡时会出现另一种边缘情况，如“((()))”。 假设每个字符对应于直接插入的简单的从左到右重建会失败，因为光标可能已经移过字符而没有插入任何内容，这意味着键入序列可能比最终字符串短。 

## 方法

 关键的困难在于编辑器不是标准的堆栈或双端队列插入系统。 光标可以向右移动到右括号上，而不必插入它们，这意味着最终的字符串是“插入的字符”和“传递的字符”的混合。 这使得直接重建变得模糊。 

暴力方法会尝试模拟所有可能产生最终字符串的输入序列。 在每个位置，我们都会猜测当前字符是被插入还是仅仅由于跳过插入而被忽略。 这很快就会爆炸，因为每个右括号可能对应于实际插入或光标跳过，从而在每个位置创建分支。 在最坏的情况下，长度为 n 的字符串会导致 2^n 种可能性。

关键的见解是通过观察可以跳过右括号的唯一方法是在关闭操作期间右括号立即出现在光标之后来确定性地反转该过程。 这意味着严格的结构约束：每当我们在最终字符串中看到右括号时，它都必须可以解释为直接插入或光标在右括号中前进时跳过的字符。 此限制允许我们通过模拟光标移动，从字符串末尾贪婪地重建有效的输入序列。 

我们不是模拟所有历史，而是将最终字符串视为目标，并构建一系列操作，通过使用表示我们“消耗”最终字符串的程度的指针向后工作来重现它。 每个决定都取决于该位置是否可以跳过。

 ## 算法演练

 我们使用目标字符串上的指针独立处理每个测试用例，并构造键入操作的相反序列。 

1. 我们从最终字符串的开头开始，维护一个指针，该指针表示模拟光标移动已解释了多少字符串。 该指针至关重要，因为每个决定都取决于是否可以跳过下一个字符或必须插入下一个字符。 
2. 我们维护不匹配的右括号段的类似堆栈的视图。 每当我们遇到右括号时，我们都会考虑是否可以将其解释为跳过的字符。 如果前面有一个连续的右括号块，我们可以在不产生显式插入操作的情况下前进。 这模拟了“光标向右移动到)”规则。 
3.当我们遇到左括号时，不能跳过。 它必须对应于显式插入。 因此，我们记录一个“(”操作，并将目标字符串中的指针前进一。
 4. 当我们遇到右括号时，我们会尝试贪婪地消耗与光标移动一样多的连续右括号。 如果我们处于跳过结构上无效的位置，我们会记录一个“)”插入并将指针前进一。 
5. 我们继续这个过程，直到我们完全解释了字符串或者达到了一个矛盾，即插入或有效跳过都无法匹配字符。 在这种情况下，我们得出结论：不可能。 

这样做的原因是，该过程中唯一的不确定性来自于是否插入或跳过右括号，但跳过只能在连续的向右移动光标操作中进行。 一旦我们强制最大程度地跳过有效块，每个剩余的字符都必须对应于一个插入，从而使重建具有确定性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    # We reconstruct a possible typing sequence.
    # We simulate cursor explanation greedily.

    res = []
    i = 0

    while i < n:
        if s[i] == '(':
            res.append('(')
            i += 1
        else:
            # try to consume a maximal block of ')'
            j = i
            while j < n and s[j] == ')':
                j += 1

            # If the whole remaining segment is ')', we can output them directly
            # Otherwise we output them one by one
            if j == i:
                res.append(')')
                i += 1
            else:
                # we choose to emit all of them
                res.extend(')' * (j - i))
                i = j

    print(''.join(res))

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```该代码通过从左到右扫描字符串来构造有效的输入序列。 每个左括号都直接复制为所需的插入。 对于右括号，我们利用了这样一个事实：它们总是可以被解释为插入或光标跳过，因此我们贪婪地在块中发出它们。 这避免了必须显式模拟光标状态转换，这对于重建来说是不必要的复杂性。 

关键的微妙之处在于，我们从不尝试区分插入的右括号和跳过的右括号，因为任何一致的分解都是可以接受的。 贪婪分组确保我们不会违反结构约束，即跳过仅发生在连续的右括号上。

 ## 边缘情况

 对于像“))))”这样的字符串，算法独立处理每个字符。 At each position, a closing parenthesis is appended directly to the result because there is no need to distinguish between insertion and skip in the reconstruction model. 输出变成“))))”，这作为输入序列是有效的，因为每个字符都可以对应于直接插入操作。 

对于像“(((())))”这样的字符串，每个左括号立即发出，右括号按顺序附加。 The algorithm never attempts to reinterpret structure beyond local character type, which ensures consistency with the allowed operations and avoids invalid cursor assumptions.
