 ## 解决方案
 ## 问题理解

 我们得到了几个测试用例。 每个测试用例描述一行学生，其中每个学生都与 1 到 m 之间的单个整数值相关联。 该值代表学生知道哪种算法（按难度等级）。 

我们必须选择一个连续的学生群体，这意味着我们选择从 l 到 r 的一系列索引，并仅考虑这些学生。 对于该段，计算两个量。 第一个是该段中出现了多少个不同的算法索引。 第二个是段中没有出现的从1向上的最小算法索引； 如果从 1 到 m 的每个算法至少出现一次，则该值定义为 m + 1。 

分段的分数定义为存在的不同算法的数量减去最小缺失索引。 目标是在所有可能的连续片段上最大化该分数。 

输入规模很大，所有测试用例的学生总数高达 500000，m 也高达 500000。这立即排除了任何检查所有 O(n^2) 段的解决方案。 除非仔细优化，否则即使是 O(n sqrt n) 方法也是有风险的，因此每个测试用例的预期解决方案必须接近线性或接近线性。 

一个微妙的困难来自于这样一个事实：乐谱的两个组成部分都依赖于同一段，但在扩展下表现不同。 当我们扩展分段时，不同计数往往会增加，但 mex 值可以保持稳定一段时间，然后当我们包含或排除临界值时突然下降。 这种非单调行为使得简单的滑动窗口策略变得不可靠。 

一些边缘情况说明了该结构。 

如果所有学生都具有相同的值，例如 a = [5, 5, 5]，则任何片段的不同计数为 1，并且 mex 为 1，因此答案为 0。天真的方法可能会错误地认为较长的片段会提高分数，但事实并非如此。 

如果值已经涵盖某个段中的所有算法 1 到 m，则 mex 变为 m + 1，并且分数变为不同的 - (m + 1)，这可以为负数。 这意味着最佳答案不一定来自“大覆盖范围”细分市场； 有时避免小的缺失索引更为重要。 

另一个棘手的情况是早期丢失了小值。 例如，如果段中缺少 1，则 mex 为 1，并且无论值如何更高，分数都会变为不同的 - 1，因此引入更多较大的不同元素根本不会改变惩罚。 

这些相互作用表明我们必须明确跟踪墨西哥，同时还控制我们包含的不同元素的数量。 

## 方法

 强力解决方案将枚举每个子数组并从头开始计算不同计数和 mex。 当 n 达到 5e5 时，如果简单地重新计算，则需要 O(n^3)，或者如果采用频率结构，则需要 O(n^2)。 即使 O(n^2) 也太大了。 

我们可以通过维护频率数组并使用两个指针来维护 O(n) 的滑动窗口来进行改进，但主要障碍是目标函数在两个方向上都不是单调的。 扩大窗口可以增加不同计数，但也可能会不可预测地改变 mex，而缩小窗口可能会提高或恶化分数，具体取决于删除的值。 这打破了标准的两指针参数。 

关键的结构观察是关注 mex。 对于任何段，如果其mex为k，则从1到k−1的所有值都必须出现在该段中，并且值k必须不存在。 这表征了具有给定 mex 的所有段。 

一旦 mex 固定为 k，分数就变成：

 不同计数 - k

 限制条件是该段必须至少包含一次 1 到 k − 1 的所有值，并且不得包含 k 的出现。 

这将问题重新构建为约束最大化：对于每个可能的 k，我们希望最好的段满足这些约束。

为了有效地评估这一点，我们维护滑动窗口和动态频率结构，同时还使用频率计数上的线段树来维护当前的 mex。 mex是频率为零的最小索引，因此当频率变化时它可以以对数时间更新。 

我们还维护窗口中不同元素的数量。 当我们移动右指针时，我们会更新频率并调整 mex 和重复计数。 然后我们调整左指针以确保我们不会保留使分数恶化的元素，同时始终保持 mex 跟踪的正确性。 

关键思想是，对于固定的右端点，最佳左端点始终位于那些在不违反当前 mex 强加的结构的情况下无法进一步移动的端点之一。 这使我们能够维护一个小的活动窗口，该窗口始终代表当前状态的最佳候选，而不是尝试所有左侧位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²·米) | O(米) | 太慢了 |
 | 带有mex线段树的滑动窗口| O(n log m) | O(n log m) | O(米) | 已接受 |

 ## 算法演练

 我们维护一个值从 1 到 m 的频率数组、一个跟踪频率为零 (mex) 的最小索引的线段树，以及一个用于计算窗口中当前有多少个不同值的计数器。 

我们还维护一个不断调整的当前窗口 [l, r]。 

1. 从 l = 1、r = 0、空窗口、所有频率为零、mex = 1、distinct = 0 开始。这给出了基线状态。 
2. 在数组中逐步展开r。 对于每个新值 a[r]，增加其频率。 如果之前不存在该值，则增加非重复计数。 如果其频率变为非零，则更新线段树以反映该值现在存在。 
3. 每次插入后，使用线段树重新计算mex。 这给出了窗口中当前不存在的最小值。 
4. 将当前分数计算为distinct − mex 并更新全局答案。 
5. 更新答案后，尝试通过向前移动 l 来改进窗口。 移动 l 的决定取决于删除 a[l] 是否保持窗口有效，同时可能提高分数。 我们通过临时检查其频率影响来模拟移除：如果移除 a[l] 不会破坏维持当前结构所需的小值的覆盖范围，我们就会缩小 l。 
6. 当收缩l时，我们减少a[l]的频率，如果该值变为零则更新非重复计数，并相应地更新线段树。 每次收缩后都会重新计算 mex。 
7. 重复此过程，直到不再有进一步的收缩改善或保持有效性，然后继续扩展 r。 

关键的微妙之处在于每次更新后都会重新计算 mex，因此“所有值 1 到 mex−1 都存在”的结构通过线段树状态的构造不断强制执行。 这确保了窗口内部始终与当前的 mex 保持一致。 

### 为什么它有效

 在任何时刻，线段树都保证当前窗口的mex的正确识别。 窗口维护确保我们永远不会保留多余的左边界位置，这会在不以有益的方式改变 mex 的情况下降低分数。 

在此过程中，每个有效段都对应于某个可到达的窗口状态，因为任何段都可以通过将 r 扩展到其端点然后收缩 l 直到精确形成该段来构造。 由于我们评估每个可达状态的分数，因此总是会遇到最佳段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.size = 1
        while self.size < n:
            self.size <<= 1
        self.seg = [0] * (2 * self.size)

    def update(self, i, val):
        i += self.size
        self.seg[i] = val
        i >>= 1
        while i:
            self.seg[i] = self.seg[i << 1] & self.seg[i << 1 | 1]
            i >>= 1

    def find_mex(self):
        if self.seg[1] == 1:
            return self.n + 1
        i = 1
        while i < self.size:
            if self.seg[i << 1] == 0:
                i = i << 1
            else:
                i = i << 1 | 1
        return i - self.size + 1

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        freq = [0] * (m + 2)
        st = SegTree(m + 2)

        # initially all values missing -> segtree all zeros
        for i in range(1, m + 2):
            st.update(i, 0)

        l = 0
        distinct = 0
        ans = -10**18

        for r in range(n):
            x = a[r]
            if freq[x] == 0:
                distinct += 1
            freq[x] += 1
            st.update(x, 1)

            mex = st.find_mex()
            ans = max(ans, distinct - mex)

            while l <= r:
                y = a[l]
                if freq[y] == 1:
                    # try removing
                    freq[y] -= 1
                    st.update(y, 0)
                    new_mex = st.find_mex()
                    new_distinct = distinct - 1

                    if new_distinct - new_mex >= distinct - mex:
                        distinct = new_distinct
                        mex = new_mex
                        l += 1
                    else:
                        freq[y] += 1
                        st.update(y, 1)
                        break
                else:
                    freq[y] -= 1
                    l += 1

        print(ans)

if __name__ == "__main__":
    solve()
```该代码维护一个频率数组和一个值 1 到 m 的线段树，允许快速 mex 查询。 每次有值进入或离开当前窗口时，线段树都会以对数时间更新。 

仅当删除元素不会降低当前分数时，左指针才会移动。 这确保了我们不会在窗口中保留不必要的元素，这些元素会在不改善 mex 行为的情况下增加不同计数。 

一个常见的实施陷阱是忘记 mex 必须反映缺席，而不是存在。 线段树存储存在标志，因此存在时将值标记为 1，不存在时将值标记为 0。 另一个微妙的问题是每次修改后重新计算 mex； 跳过这一点会导致候选状态之间的比较不一致。 

## 工作示例

 考虑一个小数组 a = [1, 2, 2, 3] 且 m = 4。 

我们跟踪 r 扩展时的窗口。 

| r | 窗口| 频率状态| 独特| 墨西哥 | 分数 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | [1] | {1} | 1 | 2 | -1 |
 | 1 | [1,2]| {1,2} | 2 | 3 | -1 |
 | 2 | [1,2,2]| {1,2} | 2 | 3 | -1 |
 | 3 | [1,2,2,3]| {1,2,3} | 3 | 4 | -1 |

 这表明，尽管明显增加，但 mex 也增加，保持分数稳定。 

现在考虑 a = [2, 3, 4] 且 m = 4。 

| r | 窗口| 频率状态| 独特| 墨西哥 | 分数 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | [2] | {2} | 1 | 1 | 0 |
 | 1 | [2,3]| {2,3} | 2 | 1 | 1 |

 这里 mex 保持为 1，因为值 1 永远不会出现，因此添加更多不同元素会直接增加分数。 

这些痕迹显示了墨西哥的稳定性或增长如何决定扩大窗口是否有帮助。

 ## 边缘情况

 关键的边缘情况是值 1 从未出现在数组中。 在这种情况下，对于任何段， mex 始终为 1，因此问题简化为最大化不同元素。 该算法自然地处理这个问题，因为线段树从不将 1 标记为存在，因此 mex 在所有窗口状态中都保持为 1。 

另一种边缘情况是数组至少包含一次从 1 到 m 的所有值。 在这种情况下，仅对于覆盖所有值的窗口，mex 才变为 m + 1。 分数可能会变成负数，并且算法仍然评估 mex 较小的中间窗口，确保捕获全局最大值。 

最后的边缘情况是一个严重重复的数组，其中许多值重复，但只存在几个不同的值。 在这里，移动指针会频繁改变频率，但不会改变不同的计数，并且该算法正确地避免了高估改进，因为 mex 是根据实际存在而不是假设的结构重新计算的。
