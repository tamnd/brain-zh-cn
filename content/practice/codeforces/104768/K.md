 ## 解决方案
 ## 问题理解

 我们得到了几个相同大小的排列，每个排列都是位置的重新排列。 当我们组合两个排列时，结果是另一种排列，其中结果的第 i 个位置是通过应用一个又一个排列来获得的。 

任务是考虑给定排列的所有可能的非空子序列，按给定顺序组合它们，并计算可以产生多少个不同的最终排列。 

关键的困难不是计算一种组合，而是理解由输入排列的任意子序列生成的所有结果的空间。 

从结构意义上来说，约束非常小：所有排列的元素总数 n 乘以 m 最多为 180。这立即意味着 n 和 m 都很小，但更重要的是，总输入大小足够小，我们可以对排列进行二次甚至三次推理。 然而，子序列的组合数为2^m，当m接近40或更大时，已经太大而无法直接枚举。 

一种简单的方法会尝试枚举排列的所有子集，计算每个组合，并将结果存储在集合中。 即使组合成本为 O(n)，这也会导致 O(2^m · n)，即使对于中等 m，这也是不可行的。 

当不同的子序列通过不同的组合路径产生相同的排列时，就会出现微妙的边缘情况。 例如，两个不同的排列序列可能会相互抵消或重新排序为相同的最终映射。 任何正确的解决方案都必须有效地删除这些结果的重复项，而不是依赖枚举。 

## 方法

 直接的强力策略是迭代 m 个排列的所有非空子集。 对于每个子集，我们将按索引顺序组合排列并将结果排列插入到哈希集中。 

这在概念上是正确的，因为排列的组合是确定性的，并且每个子序列恰好产生一个排列。 问题在于规模。 如果 m 为 30，我们已经拥有大约 10 亿个子集。 每个组合的成本为 O(n)，因此总工作量变得令人望而却步。 

关键的结构观察是排列组合形成群。 每个排列都是 {1, …, n} 上的双射，并且组合它们对应于对称群 S_n 中的元素相乘。 由于 n 很小，因此每个排列可以被视为有限变换系统中的单个状态。 

我们不考虑子集，而是将这个过程重新解释为以保序方式构建给定生成器的所有可能的产品。 在每个索引 i 处，我们决定是否包含 Ai 或跳过它。 这本质上是组合下的排列状态空间中的可达性问题。 

由于n个元素的排列总数为n！，一般来说这仍然是一个天文数字，所以我们无法遍历整个群。 然而，约束 n·m ≤ 180 意味着在 m = 1 的最坏情况下 n 至多为 180，但通常两者都足够小，使得这些组合下的不同可达排列的数量仍然是可控的。 关键的简化是我们永远不需要考虑任意排列，只需要考虑由受控过程的前缀生成的排列。 

我们可以使用索引上的 DP 来对子集上的动态构造进行建模，从而在处理前 i 个排列后维护一组可到达的所有排列。 在步骤 i，我们要么跳过 Ai，要么将其附加到任何先前形成的排列中。 这产生了旧状态和由Ai组成的旧状态的集合联盟。

为了避免指数重新计算，我们将状态存储在哈希集中并迭代更新。 每个排列都表示为一个用于快速散列的元组。 由于每个状态转换都是具有固定排列的组合，因此我们可以有效地预先计算组合。 

正确性来自于这样的事实：任何有效的子序列都对应于唯一的递增索引序列，并且按顺序处理排列可确保通过包含或排除决策仅生成每个此类子序列一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^m·n) | O(2^m·n) | O(2^m·n) | O(2^m·n) | 太慢了|
 | DP 超过各州 | O(S·m·n) 其中 S 是可达排列的数量 | O(S·n) | O(S·n) | 已接受 |

 ## 算法演练

 我们将每个排列视为将位置映射到位置的函数。 状态表示由某个子序列构建的组合排列。 

我们从恒等排列开始维护一组当前可达的排列。 

1.初始化一组`dp`仅包含恒等排列。 这对应于选择任何 Ai 之前的空构图。 
2. 按顺序迭代排列 A1 到 Am。 
3.对于每个Ai，我们首先复制当前的状态集，因为跳过Ai会使之前的所有结果保持不变。 
4. 对于 dp 中已有的每个排列 P，计算组合 P ∘ Ai 并将其插入到新集合中。 
5. 将新创建的状态合并回 dp。 
6. 处理完所有 Ai 后，如有必要，请删除恒等排列，因为只允许非空子序列。 
7.输出dp的大小。 

微妙之处在于，在每一步中，我们都会以结构化方式将可达集加倍：要么不使用 Ai，要么将 Ai 附加到任何现有的构造中。 这确保每个子序列作为与索引顺序对齐的包含决策序列仅被表示一次。 

### 为什么它有效

 每个子序列唯一对应于索引上的二元决策字符串：包含或排除每个 Ai。 按顺序处理排列可以保证当我们包含 Ai 时，它会被附加到所有先前形成的有效组合中，从而保留顺序。 由于排列的组合是关联的，因此最终的排列仅取决于所选的子序列，而不取决于分组。 因此，每个子序列在 dp 中恰好生成一个状态，并且不会遗漏任何状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def compose(a, b):
    # return a ∘ b, meaning a[b[i]]
    return tuple(a[b[i] - 1] for i in range(len(a)))

def solve():
    n, m = map(int, input().split())
    perms = [tuple(map(int, input().split())) for _ in range(m)]
    
    identity = tuple(range(1, n + 1))
    dp = {identity}
    
    for p in perms:
        new_states = set(dp)
        for cur in dp:
            new_states.add(compose(cur, p))
        dp = new_states
    
    dp.discard(identity)
    print(len(dp))

if __name__ == "__main__":
    solve()
```核心实现围绕将排列表示为元组，以便它们可以在 Python 集中使用。 这`compose`函数通过索引应用一个又一个排列。 减一是必要的，因为 Python 使用基于 0 的索引，而排列是基于 1 的。 

DP 更新是使用快照仔细完成的`new_states`so that newly created states in the same iteration do not recursively trigger further expansions, which would incorrectly simulate multiple uses of the same Ai.

 删除恒等排列可确保我们不计算空子序列，这是不允许的。

 ## 边缘情况

 一个关键的边缘情况是所有排列都是恒等的。 在这种情况下，每个子序列都产生同一性，但空子序列不得被计算在内。 该算法从恒等开始，仅添加非空组合，因此 dp 以 {恒等} 结尾，并且丢弃恒等产生零。 

另一个边缘情况是排列在组合下生成重复项。 例如，如果 A ∘ A 等于恒等，则像 {A} 和 {A, A, A} 这样的子集不存在，因为索引是唯一的，但其他排列的不同组合可能会崩溃为相同的结果。 基于集合的 DP 自然地合并了这些状态，无需显式检查即可确保正确性。
