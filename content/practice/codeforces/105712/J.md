 ## 解决方案
 ## 问题理解

 我们给出了几个测试用例，每个测试用例描述了从 1 到 n 的整数排列。 这里的排列只是一个数组，其中从 1 到 n 的每个数字都只出现一次。 

任务是确定此排列是否具有特殊的对称性：如果将数组视为从位置到值的映射，然后应用该映射两次，则将返回到每个元素的起始位置。 换句话说，如果您从索引 i 到 p[i]，然后从 p[i] 到 p[p[i]]，那么对于所有 i，您最终应该回到 i。 

每个测试用例的输出是对该属性是否成立的简单判断。 

尽管问题看起来与数组有关，但底层结构是有限集上的函数。 每个索引都指向另一个索引，我们正在检查这个函数是否是它自己的逆函数。 

这里没有明确提供约束，但这种形式的典型排列问题每个测试用例至少有 10^5 个元素。 这立即排除了任何二次模拟。 任何试图在不缓存的情况下重复跟踪每个索引中的链的方法在最坏的情况下都会降级为 O(n^2)，这是不可行的。 每个测试用例我们需要一次线性扫描。 

一些边缘情况往往会打破天真的推理。 

一种是变相的自循环。 例如，如果 n = 1 并且排列为 [1]，则该条件通常成立，因为应用映射两次仍保持在 1。粗心的实现假设循环的长度必须至少为 2，可能会对此进行错误处理。 

另一种情况是混合循环。 例如，n = 4 且 p = [2,1,4,3]。 这实际上是有效的，因为它由不相交的交换组成，但是仅检查本地一致性（例如 p[i] != i）的错误方法可能会错误地拒绝它。 

当排列在局部具有有效的对合结构但在全局不具有有效的对合结构时，会发生更微妙的失败。 例如，p = [2, 3, 1] 看起来是循环的，但应用两次并不会将所有元素返回到其起始位置。 

## 方法

 一种直接的方法是按字面模拟条件。 对于每个索引 i，我们计算 p[p[i]] 并将其与 i 进行比较。 如果出现任何不匹配，我们立即拒绝排列。 

这是正确的，因为每个索引的条件是独立的。 每个索引必须满足其自身的约束，因此检查所有索引就足够了。 

然而，这需要仔细处理索引和重复访问排列数组。 每次检查的时间复杂度为 O(1)，我们执行 n 次，因此每个测试用例的总时间为 O(n)。 在所有测试用例中，这与总输入大小保持线性关系。 

一个强力的误解是尝试明确地探索循环，标记访问过的节点并重建结构。 这仍然有效，但会引入不必要的簿记，而不会改变复杂性。 另一个更糟糕的变体是模拟每个索引的排列的重复应用，这会导致 O(n^2) 行为。 

关键的观察是我们不需要构建循环或模拟步骤。 条件 p[p[i]] = i 已经充分表征了排列是否是对合。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个索引重复步骤的强力模拟 | O(n^2) | O(n^2) | O(n) | 太慢了|
 | 直接检查所有 i 的 p[p[i]] = i | O(n) | O(n) | 已接受 |

 ## 算法演练

1. 读取n和排列数组p。 该数组概念上是 1 索引的，但存储在 0 索引的 Python 列表中，因此在访问值时需要进行调整。 这很重要，因为索引库之间的混淆是此处错误答案的最常见来源。 
2. 对于从 0 到 n - 1 的每个索引 i，计算值 j = p[i]。 这代表从 i 开始映射的第一步。 
3. 如果使用 1 索引逻辑，则检查 p[j - 1] 是否等于 i + 1，或者以 0 索引形式检查 p[p[i] - 1] == i。 如果这个等式对于任何 i 都失败，则排列不能是它自己的逆，所以我们可以提前停止。 
4. 如果所有索引都满足条件，则声明排列有效。 

提前停止有效的原因是该属性在所有指数中都是合取的。 一次违规会使整个排列无效。 

### 为什么它有效

 由排列定义的映射是集合 {1, ..., n} 上的双射。 条件 p[p[i]] = i 意味着应用该函数两次会产生恒等函数。 这正是对合的定义。 由于对每个元素逐点检查相等性，因此对每个索引进行本地验证可以保证全局正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_case(n, arr):
    for i in range(n):
        j = arr[i] - 1
        if arr[j] != i + 1:
            return False
    return True

def main():
    out = []
    while True:
        line = input().strip()
        if not line:
            break
        n = int(line)
        if n == 0:
            break
        arr = list(map(int, input().split()))
        if solve_case(n, arr):
            out.append("ambiguous")
        else:
            out.append("not ambiguous")
    print("\n".join(out))

if __name__ == "__main__":
    main()
```核心逻辑位于`solve_case`。 每个元素i用于跳转一次到j = p[i] - 1，然后我们验证从j跳回是否返回到i。 减法和加法调整是必要的，因为输入是从 1 开始的，而 Python 列表是从 0 开始的。 

循环中`main`一直持续到 n = 0，这是此问题的标准终止模式。 当存在多个测试用例时，逐行读取可以避免输入不同步问题。 

## 工作示例

 考虑 n = 4 且排列为 2 1 4 3 的输入。 

| 我| p[i] | p[i] j = p[i]-1 | p[j] | p[j] | 检查|
 | ---| ---| ---| ---| ---|
 | 0 | 2 | 1 | 1 | 好的 |
 | 1 | 1 | 0 | 2 | 好的 |
 | 2 | 4 | 3 | 3 | 好的 |
 | 3 | 3 | 2 | 4 | 好的 |

 每个索引都满足条件，因此排列有效。 该迹线显示了完全由 2 圈组成的结构，它自然满足对合性质。 

现在考虑 n = 3 和排列 2 3 1。 

| 我| p[i] | p[i] j = p[i]-1 | p[j] | p[j] | 检查 |
 | ---| ---| ---| ---| ---|
 | 0 | 2 | 1 | 3 | 失败|

 第一次检查已经失败，因为两次映射不会返回到起点。 这表明长度大于 2 的循环排列不能满足该条件。

 ## 边缘情况

 对于 n = 1，必须接受排列 [1]。 该算法检查 i = 0，计算 j = 0，并验证 arr[0] == 1，该结果成立，因此返回有效。 

对于完全由固定 2 周期组成的排列，例如 [2, 1, 4, 3]，每个索引在两次应用后都会正确映射回来。 该算法独立验证每一对，因此不需要全局循环推理。 

对于单个大循环（例如 [2, 3, 4, 1]），第一个索引已经不符合条件，因为两次映射不会返回到开头。 该算法会立即检测到这一点，而无需遍历整个循环结构。
