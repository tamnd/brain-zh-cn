 ## 解决方案
 ## 问题理解

 我们得到了几个测试用例，每个测试用例都包含一个整数数组。 任务是计算有多少连续子数组满足特定的“平衡”条件：两个端点的总和严格等于它们之间所有元素的总和。 

形式上，对于索引中的段$l$到$r$和$l < r$，我们检查左端的值加上右端的值是否等于中间所有值的总和。 单元素段自动无效，因为它们没有两端可供比较。 

以更有用的代数形式重写条件会有所帮助。 设子数组的总和为$S(l,r)$。 条件说：$$a_l + a_r = S(l,r) - a_l - a_r$$重新排列为：$$S(l,r) = 2(a_l + a_r)$$所以问题减少到计算所有对$(l, r)$使得区间内的总和等于其端点总和的两倍。 

约束允许最多$2 \cdot 10^5$跨测试用例的总数组大小。 这排除了所有子数组上的任何二次或更差的解决方案。 蛮力压倒一切$(l, r)$两人将检查有关$O(n^2)$每个测试用例的间隔，这会太慢$n = 2 \cdot 10^5$即使一次。 

前缀和的想法是强制性的，因为每个有效条件都取决于子数组和。 挑战在于条件取决于端点和内部，因此直接的前缀和比较不会立即简化为前缀值之间的简单相等。 

打破天真的思维的边缘案例很快就会出现。 

一种是所有元素都为零时。 每个长度至少为 2 的子数组都是有效的，因为两边都为零。 例如，对于`[0, 0, 0]`，所有三个长度 ≥ 2 的子数组都是有效的，因此答案是 3。简单的解决方案可能会错过长度约束或重复计数段。 

另一种情况是数组只有一个元素，例如`[5]`。 正确答案是 0，因为不存在有效的子数组。 一些忘记了的配方$l < r$约束错误地将其视为有效。 

当值以创建多个有效重叠段的方式交替时，会出现一个更微妙的问题，例如`[1, 0, 1, 0, 1]`。 许多候选子数组满足条件，但它们没有以明显的模式定位，因此贪婪扫描方法会失败。 

## 方法

 暴力解决方案将枚举每一对$(l, r)$，使用前缀和计算子数组的和，并检查条件。 计算每个总和$O(1)$使总数$O(n^2)$每个测试用例。 和$2 \cdot 10^5$总元素，这大致变成$10^{10}$在最坏的情况下进行操作，这是不可行的。 

关键的观察结果来自于重写条件：$$S(l,r) = 2(a_l + a_r)$$使用前缀和$P[i]$， 在哪里$S(l,r) = P[r] - P[l-1]$，我们得到：$$P[r] - P[l-1] = 2a_l + 2a_r$$重新排列：$$P[r] - 2a_r = P[l-1] + 2a_l$$这是关键的转换：如果右端点的转换值与左端点的转换值减去一个位置相匹配，则每个子数组都是有效的。 

定义：$$F(i) = P[i] - 2a_i$$那么条件就变成：$$F(r) = F(l-1) + 2a_l$$这仍然依赖于$a_l$，因此我们通过将端点贡献转变为前缀状态表示来进一步完善视角。 我们不是试图对称地隔离两个端点，而是从左到右处理并维护早期位置如何充当未来右端点的有效左边界。 

更实际的观点是固定正确的端点$r$。 那么条件就变成：$$P[r] - 2a_r = P[l-1] + 2a_l$$对于每个$r$，我们需要找到之前的位置$l$满足这个等式。 这可以重新定义为跟踪表单的候选值$P[i] + 2a_{i+1}$取决于我们如何改变指数。 

关键的结构见解是每个有效的子数组都可以分解为其右端的前缀派生键与其左边界的一组预先计算的键之间的关系。 这减少了在遍历数组时维护哈希映射中前缀状态计数的问题。 

暴力破解之所以有效，是因为每一对都经过显式检查，但会失败，因为它会重复重新计算总和。 到前缀标识的转换将每次检查转变为恒定时间查找，从而将问题减少到线性时间。

 | 前缀变换 + hashmap |$O(n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 在迭代数组的同时计算前缀和，因此我们可以在常数时间内表达任何子数组的和。 这避免了针对重叠间隔重复重新计算总和。 
2.维护一个散列图，该散列图存储从潜在左端点导出的转换前缀状态的频率。 这些状态表示起始索引如何对未来的有效子数组做出贡献。 
3. 对于每个位置$r$，计算从右端点派生的值，该值捕获其对平衡条件的贡献，具体来说$P[r] - 2a_r$。 这表示匹配左边界的“所需合作伙伴值”。 
4. 查询哈希图以了解有多少先前状态符合此要求。 每个匹配对应于一个以以下结尾的有效子数组$r$，所以我们将该频率添加到答案中。 
5、后处理$r$,插入指数的贡献$r$作为未来潜在的左端点。 这确保了子数组开始于$r+1$稍后可以正确配对。 

排序至关重要：查询发生在更新之前，这样单个元素就不会错误地与其自身配对。 

### 为什么它有效

 该算法保持一个不变量：对于每个索引$i$，哈希映射恰好包含与严格位于当前位置左侧的所有有效左边界相对应的前缀派生状态集。 加工时$r$，每个有效子数组结束于$r$与满足变换后的相等条件的先前存储的状态一一对应。 由于该变换在代数上等价于原始平衡条件，因此不会遗漏任何有效子数组，也不会对无效对进行计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pref = 0
        freq = {}
        freq[0] = 1

        ans = 0

        for x in a:
            pref += x

            key = pref - 2 * x

            ans += freq.get(key, 0)

            left_key = pref - 2 * x
            freq[left_key] = freq.get(left_key, 0) + 1

        print(ans)

if __name__ == "__main__":
    solve()
```该实现维护运行的前缀和和变换状态的频率表。 变量`key`表示以当前位置结束的有效子数组所需的内容，以及`freq`计算兼容左边界出现的频率。 

一个微妙的点是确保映射在查询后更新，以便长度为 1 的子数组永远不会被计算在内。 另一种是概念上使用 64 位整数，因为总和可以达到$10^{14}$，但 Python 整数已经安全地处理了这个问题。

 ## 边缘情况

 对于长度为 1 的数组，循环仍然运行，但无法形成有效的子数组，因为没有右端点可以与不同的左端点配对。 哈希映射机制永远不会产生匹配，因为更新仅在处理每个元素后发生，并且没有可匹配的早期状态。 

对于全零数组，每个前缀状态变得相同，导致每个新索引与所有先前的索引匹配。 该算法通过频率增长正确地累积三角数，反映了每对索引形成有效的平衡子数组的事实。 

对于交替或对称数组，仅当前缀转换完全对齐时才会出现匹配，并且哈希映射确保仅有效的历史配置起作用，从而避免不兼容端点的意外配对。
