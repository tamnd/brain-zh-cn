 ## 解决方案
 ## 问题理解

 我们正在模拟一个非常简单的生产过程，随着时间的推移，哈维尔拥有的光盘数量会增加。 他从一张光盘开始。 每分钟他都会选择一些棋子，将它们放入机器中，一分钟后机器会将两倍数量的棋子返回到他的池中。 他不使用的光盘仍然可用，因此系统的行为就像一个不断增长的库存。 

形式上，如果他在 i 分钟之前的当前库存为 c，并且他选择了 x 盘，那么他必须有 x 可用，并且在该分钟之后他的库存变为 c - x + 2x，从而简化为 c + x。 所选数量实际上是添加到当前库存的增量，但受到 x ≤ c 的限制。 

m 分钟后，库存必须恰好为 n。 我们被要求最小化 m，并在 m 步达到 n 的所有最佳方法中，输出所选值 x₁、x2、…、xₘ 的字典顺序最小序列。 

约束 n ≤ 10^9 足够大，以至于不可能进行 O(n) 模拟。 任何解决方案都必须将问题简化为对数或贪婪的问题，因为在最佳使用时，过程会呈指数级快速增长。 

一些边缘情况值得隔离。 

如果 n = 2，则该过程必须一步从 1 到 2，因此强制 x₁ = 1。 

如果 n 很大但接近 2 的幂，那么除非我们仔细确保精确的可达性，否则总是加倍的天真贪婪可能会过冲或下冲。 

关键的微妙之处在于，虽然我们希望快速增长以最小化 m，但我们还需要精确控制最终总和，因为每个 x 都会做出附加贡献，并且必须在 x ≤ 当前库存的约束下保持可行。 

## 方法

 蛮力策略将模拟每分钟 x 的所有可能选择。 在步骤 i，使用当前库存 c，我们可以尝试从 1 到 c 的所有 x，递归地探索所有结果状态。 这种分支很严重：状态数量在 m 步上大致像 c × c × c 一样增长，即使对于较小的 n，也会变得天文数字般大。 原因是状态空间并没有缩小，每一个选择都会创造另一个全方位的选择。 

该过程的结构表明了一种更强的模式。 由于每次操作都会将 x 添加到当前库存中，因此减少步骤数的最佳方法是在每个阶段使 x 尽可能大。 约束 x ≤ c 意味着最大可能的增长是 x = c，这使得库存翻倍。 这立即意味着库存增长速度不能超过每分钟翻倍，因此从 1 达到 n 至少需要大约 log2 n 步。 

这给出了 m 的下界。 更困难的部分是证明这个界限是可以准确实现的，同时仍然落在 n 上，而不仅仅是超过它。 解决方案是向后构建流程。 我们不是向前决定x，而是决定每一步之后的库存必须是多少，确保其增长速度永远不会超过一倍，然后从差异中恢复x。 

这种向后的构造产生了一个独特的最小长度状态序列，并且从这些状态中确定性地遵循字典顺序的最小移动序列。

 ## 算法演练

1、m分钟后从最终需要的库存n开始。 我们还不知道 m，但我们知道该过程的增长速度不能超过一倍，因此我们反复应用反向转换：前一个库存必须至少是下一个库存的一半。 
2. 定义 cₘ = n 并计算 cᵢ₋₁ = ceil(cᵢ / 2)。 这给出了在一次有效的移动中可以达到 cᵢ 的最小可能的先前状态。 出现上限是因为 cᵢ 最多必须是 cᵢ₋₁ 的两倍。 
3. 重复步骤 2，直到达到 c₀ = 1。执行的反向步骤数是最小 m。 
4. 一旦知道所有状态 c₀、c₁、…、cₘ，就向前计算操作。 对于每个 i，设置 xᵢ = cᵢ − cᵢ₋₁。 这正是那一分钟添加的数量。 
5. 输出 m 和序列 x₁, …, xₘ。 

重建有效的原因是每个前向步骤自动满足约束：由于通过构造 cᵢ ≤ 2cᵢ₋₁，我们总是有 xᵢ = cᵢ − cᵢ₋₁ ≤ cᵢ₋₁，这确保了可行性。 

字典顺序最小的条件是通过向后构造强制执行的：在每一步选择尽可能小的先前状态，迫使早期增量尽可能小，同时仍然允许在最短的时间内完成。 任何减少早期 xᵢ 的尝试都会迫使后来的状态增长得比允许的更快，从而增加 m。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

states = [n]

# build states backward until reaching 1
while states[-1] > 1:
    c = states[-1]
    prev = (c + 1) // 2
    states.append(prev)

states.reverse()

m = len(states) - 1
print(m)

res = []
for i in range(1, len(states)):
    res.append(states[i] - states[i - 1])

print(*res)
```该解决方案首先使用最严格的可能前驱规则向后构造可达股票值的序列。 表达式 (c + 1) // 2 是 ceil(c / 2) 的整数形式，它保证将前驱加倍永远不会低于 c。 

反转后，列表表示在每一步最多只能是前一个库存的两倍的约束下，从 1 到 n 的唯一最小长度轨迹。 连续状态之间的差异给出了实际的 x 值。 

一个常见的陷阱是尝试直接按前向顺序决定 x。 这种方法失败了，因为局部贪婪选择不能保持全局可行性； 落后的建设首先在全球范围内增强可行性。 

## 工作示例

 ### 示例 1：n = 8

 落后建设：

 | 步骤| c（目标）| 上一个 = ceil(c/2) |
 | ---| ---| ---|
 | 4 | 8 | 4 |
 | 3 | 4 | 2 |
 | 2 | 2 | 1 |

 所以状态是[1,2,4,8]。 

正向重建：

 | 我| cᵢ₋₁ | | cᵢ | xᵢ |
 | ---| ---| ---| ---|
 | 1 | 1 | 2 | 1 |
 | 2 | 2 | 4 | 2 |
 | 3 | 4 | 8 | 4 |

 输出分为 3 个步骤：1 2 4。 

这证实了每个步骤的过程都会加倍，从而实现尽可能短的时间。 

### 示例 2：n = 10

 落后建设：

 10 → 5 → 3 → 2 → 1

 状态：[1,2,3,5,10]

 正向 x 值：

 | 我| cᵢ₋₁ | | cᵢ | xᵢ |
 | ---| ---| ---| ---|
 | 1 | 1 | 2 | 1 |
 | 2 | 2 | 3 | 1 |
 | 3 | 3 | 5 | 2 |
 | 4 | 5 | 10 | 10 5 |

 这表明，当 n 不是 2 的幂时，该过程自然会尽早引入较小的增量以保持可行，同时在以后仍保持尽可能的积极性。

 ## 边缘情况

 对于 n = 2，后向过程立即生成 2 → 1，从而给出 m = 1 且 x₁ = 1。该算法会处理此问题，因为 ceil(2/2) = 1 立即终止。 

对于 2 的幂，每次反向减半都保持精确，从而产生干净的双倍链。 没有舍入，因此该序列成为严格的几何级数。 

对于奇数值，上限操作确保我们永远不会选择太小而无法达到当前值的先前状态。 例如，从 5 到 3，因为 2·2 = 4 是不够的，而 2·3 = 6 是有效的。 

每个案例都表明，在每一步中都保留了不变的 cᵢ ≤ 2cᵢ₋₁，这是构建的核心可行性条件。
