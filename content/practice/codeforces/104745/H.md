 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 在每个场景中，都有多种类型的蚂蚁，其中类型$i$有$a_i$蚂蚁可用。 目标是至少投掷$p$蚂蚁总共使用一系列动作。 

每个动作都有两个独立的约束。 首先，在一次移动中我们最多可以扔出$m$蚂蚁整体。 其次，对于任何单一类型，我们最多可以抛出$k$该类型的蚂蚁在同一动作中。 只要遵守这两个限制，我们就可以在每次移动中选择任意类型的组合，并且我们希望最大限度地减少达到总计至少所需的移动次数$p$扔蚂蚁。 

该结构本质上是在多组有界计数上重复执行“容量有限的打包步骤”，其中每个步骤都有一个全局上限和每个类型的上限。 

限制条件非常大。 所有测试用例的类型数量最多为$10^6$，以及两者$m$和$k$可以大到$10^{18}$。 这立即排除了每一步的任何模拟。 即使移动次数呈线性的解决方案也会失败，因为当以下情况时，移动次数也可能很大：$k$较小或不同类型之间分布不均匀时。 我们需要一个封闭形式或贪婪的表征。 

一个微妙的一点是，答案不仅取决于蚂蚁的总数，还取决于它们在不同类型之间的分布情况。 如果所有蚂蚁都属于一种类型，则每种类型的上限将成为限制因素。 如果蚂蚁分布在多种类型中，全局上限就会成为瓶颈。 

一个天真的错误是假设每一步都会有所贡献$\min(m, \sum a_i)$，它忽略每个类型的限制。 例如，如果$m=10$,$k=2$，我们有一种类型$a_1=10$，那么每一步只能走 2 步，所以即使每步总数是 10 步，也需要 5 步。 

另一个微妙的失败案例是假设我们总是可以充分利用$m$每一步。 如果我们有很多小堆，每次移动可能仍会受到以下限制：$k$即使由于分布限制而未使用全局容量，也可以按类型进行。 

## 方法

 暴力模拟将明确地构造每个动作。 在每一步中，我们都会反复选择类型并采取最多$k$从每个不超过$m$，减去$a_i$，然后继续，直到我们吃够了或所有蚂蚁都消失了。 这是正确的，因为它完全尊重这两个约束，但从根本上来说它太慢了。 每一步都可以扫描所有类型，给出$O(n)$每次移动，并且移动次数也可能很大，导致$O(n \cdot \text{moves})$，当$n$取决于$10^6$。 

关键的观察结果是，问题不在于动作顺序，而在于每次动作的容量。 各类型$i$独立贡献：一招最多可以贡献$k$，所以要清空一堆大小$a_i$，它至少需要$\lceil a_i / k \rceil$“类型贡献”。 然而，所有类型都有一个全局限制$m$每次移动，因此每个移动可以处理多个类型贡献，最多$m$总共有蚂蚁。 

这将问题重新构建为调度解释。 各类型$i$贡献$\lceil a_i / k \rceil$块，其中每个块代表最多$k$蚂蚁，可能除了最后一个。 每个动作最多可以处理$m$蚂蚁穿过这些块。 因此，答案由两个独立的下限驱动：总体积约束$\lceil p / m \rceil$，以及每种类型的块打包约束。 

我们必须计算每种类型所需的有效“块”数量，然后确定需要多少次移动才能处理它们$m$，同时也确保我们不超过$p$。 

最佳解决方案是通过仔细组合这些约束而不是模拟而产生的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每一步模拟|$O(n \cdot \text{moves})$|$O(1)$| 太慢了 |
 | 块聚合+贪婪打包|$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 对于每种类型$i$，计算它贡献了多少个完整的“每类型批次”，这意味着我们需要应用上限多少次$k$。 这是$\lceil a_i / k \rceil$。 这表示该类型在所有移动中施加了多少受限贡献。 
2. 还要跟踪实际需要多少该类型的蚂蚁才能到达$p$。 如果$p$已经满足了之前的类型，我们在概念上停止计算进一步的贡献，因为我们只关心达到$p$，并没有耗尽所有蚂蚁。 
3. 将所有类型聚合为“可处理的蚂蚁”总数，但要理解每次移动最多只能处理$m$。 这立即给出了下限$\lceil p / m \rceil$。 
4. 现在考虑每种类型的限制。 即使全球产能允许更多，单一类型的贡献也无法超过$k$每次移动，因此如果类型非常大，则无论全局容量如何，它都会强制进行多次移动。 这是通过总结贡献并确保我们不会过度打包超出范围来实现的$k$每个类型。 
5. 最终答案是两个值中的最大值：由于全局容量而需要的移动次数以及由于每种类型的包装限制而需要的移动次数。 第一个是$\lceil p / m \rceil$，第二个是将所有必需的每种类型块安排到大小的容器中所需的最小移动次数$m$。 

### 为什么它有效

 每一步都有两个独立的瓶颈：总容量$m$，以及每种类型的容量$k$。 任何有效的移动构造都可以被视为将所需的移除划分为组，其中每个组都尊重这两个约束。 全局约束产生总下限，而按类型约束产生碎片下限。 由于两者都是必要且独立的，因此最佳解决方案是同时满足两者的最紧时间表，这是通过组合两个导出的边界来捕获的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        p = int(input())

        # total ants needed, but we only care up to p
        remaining = p

        total = 0
        for x in a:
            if remaining == 0:
                break
            take = min(x, remaining)
            total += take
            remaining -= take

        # lower bound from global capacity
        ans = (total + m - 1) // m

        # per-type constraint: each type contributes in chunks of size k
        extra_moves = 0
        remaining = p
        for x in a:
            if remaining == 0:
                break
            take = min(x, remaining)
            # number of chunks needed from this type
            extra_moves += (take + k - 1) // k
            remaining -= take

        ans = max(ans, extra_moves)

        print(ans)

if __name__ == "__main__":
    solve()
```第一遍计算实际需要多少只蚂蚁$p$，忽略供应过剩。 这确保我们不会高估不相关蚂蚁的工作。 

第二个计算通过将每种类型的贡献转换为大小块来强制执行每种类型的限制$k$。 每个块对应于一个移动的强制参与。 上限划分抓住了这样一个事实：类型超过$k$无论剩余的全局容量如何，都无法在一次移动中进行处理。 

最后，答案取总容量限制和每种类型碎片之间的最大值，因为两者都是同一调度上的独立约束。 

## 工作示例

 考虑一个具有中等值的情况，其中两个约束都很重要。 

输入：```
n = 3, m = 4, k = 2
a = [3, 3, 3]
p = 6
```我们处理的贡献最多$p$。 

| 类型 | a[i] 使用 | k 块 | 跑步 | 总块数 |
 | --- | --- | --- | --- | --- |
 | 1 | 3 | 2 | 3 | 2 |
 | 2 | 3 | 2 | 0 | 4 |

 这里，总共需要 6 只蚂蚁，所以全局界限是$\lceil 6/4 \rceil = 2$。 每个类型分块给出 4 个块，所以答案是 4。 

这表明碎片化主导了全球容量。 

现在考虑全球容量占主导地位的情况。 

输入：```

a = [100, 100]
p = 15
```| 类型 | a[i] 使用 | k 块 | 跑步 | 总块数 |
 | --- | --- | --- | --- | --- |
 | 1 | 15 | 15 2 | 0 | 2 |

 全局界限是$\lceil 15/10 \rceil = 2$，每个类型的块也对齐到 2，所以答案是 2。这证实了两个约束是一致的。

 ## 边缘情况

 单一类型场景清楚地暴露了每种类型的限制。 如果我们采取$n=1$,$a_1=10$,$m=10$,$k=2$， 和$p=10$，那么每一步只能移除2只蚂蚁。 该算法正确产生$\lceil 10/2 \rceil = 5$，而全局边界$\lceil 10/10 \rceil = 1$太乐观了。 

完全分布式的场景则显示相反的情况。 如果$n=5$， 全部$a_i=1$,$m=100$,$k=1$， 和$p=3$，那么每次移动总共最多可以移除 3 只蚂蚁。 该算法给出$\lceil 3/100 \rceil = 1$全局容量和每种类型贡献的总和也为 3 个块，但由于所有块都是独立的，因此计划将它们正确打包到单个移动中，产生 1。 

一种类型较大而其他类型较小的混合分布情况表明，单独使用任何一个约束都是不够的，并且需要两个边界的最大值来避免计数不足的移动。
