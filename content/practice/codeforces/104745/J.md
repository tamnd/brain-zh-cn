 ## 解决方案
 ## 问题理解

 我们给出了几个独立的场景。 每个场景都有一个目标值$x$代表赤字必须精确为零。 我们还有$n$学生，每个人都有一个初始权力$a_i$。 

时间以离散的日子演变。 每一天，每个学员的力量都会增加整整一分。 在任何时刻，Esomer 都可以选择一个学生并使用他们一次，这会立即从剩余的值中减去该学生当前的力量$x$。 一旦学生被使用，他们将不再被使用。 目标是选择选择顺序和每个学生使用的日期，以便所选贡献的总和恰好为$x$，并且实现这一目标所需的天数被最小化。 

塑造解决方案的关键约束是$n$和$x$最多 200 个，所有的总和$n$和$x$测试用例的数量也以 200 为界。这立即表明了对状态的动态规划方法，涉及我们处理了多少学生以及我们积累了多少价值，因为超过 200 的二次或三次转换很容易实现。 

当所有贡献增长缓慢并且我们被迫等待几天才能达到任何有用的组合时，就会出现微妙的边缘情况$x$。 另一个原因是，过早挑选实力较强的学生并不是最理想的，因为延迟会增加他们的贡献，足以减少总等待时间。 

天真的贪婪策略，例如总是选择当前最强的学生或总是在可用时立即选择，会失败，因为使用的时机与学生的身份一样重要。 

例如，考虑$n=2, x=5$， 和$a=[2,3]$。 立即使用两者给出$2+3=5$，所以答案是 0。但是如果$a=[1,1,1]$和$x=3$，您可能需要等待数天，以便减少选择就足够了，因为每个学生都会随着时间的推移而成长。 当增长随着时间的推移改变顺序时，任何贪婪的“先取最大”的推理都会被打破。 

## 方法

 蛮力视图是在几天内模拟该过程。 每天，未使用的学生的每个子集都有一个由下式确定的当前值：$a_i + d$，我们尝试跨天选择学生的所有组合，直到累计总和等于$x$。 这种爆炸式的增长是因为我们每天都在有效地探索剩余学生的子集，从而导致指数数量的选择和对相同子结构的重复重新计算。 

失败之处在于，学生的贡献完全由两个参数决定：我们何时挑选他们以及是哪个学生。 绝对日期仅与他们在被选择之前收到的增量有关。 这表明我们不应该直接模拟天数，而是根据每个所选学生相对于全局时间获得的增量进行推理。 

如果学生在白天被选中$d$，他们的贡献是$a_i + d$。 如果我们选择$k$学生总数，最后一次挑选发生在当天$D$，每个选定的学生对应于中不同日期的选择$[0, D]$。 这将问题转化为选择$k$学生并分配他们增加天数，这自然会导致我们录取了多少学生以及我们获得了多少总金额的DP，同时跟踪天数与选择顺序的相互作用。 

关键转型是固定使用学生数量$k$，并计算我们可以达到的最大总和$D$天，或者同等地测试我们是否可以达到$x$和$k$内挑选$D$。 然后我们最小化$D$。 自从$x \le 200$，我们可以把问题反过来：对于一个固定的$k$，计算可以达到总和的最早一天$x$，使用 DP，其中每个州跟踪有多少学生被选择以及累积的总金额，同时考虑到以下事实：$j$- 第一个被选中的学生根据其在选择时间线中的位置贡献额外的增量。 

这导致了一个标准的背包式DP，我们决定是否在选择序列中的某个位置选择一个学生，并且成本取决于已经进行了多少次选择。

 | 暴力模拟| 指数| 指数| 太慢了 |
 | DP 选秀权和总和 |$O(n \cdot x \cdot n)$|$O(x \cdot n)$| 已接受 |

 ## 算法演练

 我们将这个过程视为选择学生的有序序列。 假设我们决定准确地选择$k$学生。 如果使用学生作为$j$-th pick (0-indexed)，我们在之后完成$k-1$天，然后该学生贡献$a_i + j$。 这是因为每次选秀都对应一天，所有尚未选秀的学生都统一增加了。 

这消除了显式时间模拟并用排序结构代替。 

### 步骤

 1. 对于每个可能的选择数$k$从 1 到$n$，我们计算是否可以精确地达到$x$使用$k$学生。 

我们分开的原因$k$时间成本与连续挑选的数量直接相关。 
2.对于固定的$k$，我们运行一个 DP，其中$dp[j][s]$意味着我们是否可以准确地选择$j$学生缴款总额$s$，假设贡献根据位置效应进行调整。 

这隐式地捕获了选择和排序。 
3. 考虑具有基础价值的学生时$a_i$，如果选择它作为$j$-th 选秀权，其有效贡献为$a_i + j$。 

这意味着转换必须添加两者$a_i$和当前的选择索引。 
4. 我们对学生进行一一处理，逆向更新DP$j$以避免重复使用。 

这确保每个学生最多被使用一次。 
5. 给定的DP填充后$k$，我们检查是否存在达到总和的配置$x$。 

如果是，候选答案是$k-1$， 自从$k$选秀要求$k-1$天。 
6.我们返回最小有效值$k-1$跨越所有可行的$k$。 

### 为什么它有效

 核心不变量是任何有效的策略都唯一对应于所选学生的排序，并且该排序决定了每个学生收到的增量数量和使用的总天数。 通过将问题编码为“选择$k$“按顺序排列项目并分配递增的偏移量，”我们保留所有有效的时间线，而无需显式模拟时间。每个真实的流程都准确地映射到一个 DP 构造，并且每个 DP 构造都对应于有效的选择时间表，因此不会丢失或重复计算解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))

        INF = 10**9
        ans = INF

        for k in range(1, n + 1):
            # dp[j][s]: using j picks, sum s achievable
            dp = [[False] * (x + 1) for _ in range(k + 1)]
            dp[0][0] = True

            for ai in a:
                for j in range(k - 1, -1, -1):
                    for s in range(x + 1):
                        if not dp[j][s]:
                            continue
                        val = s + ai + j
                        if val <= x:
                            dp[j + 1][val] = True

            if dp[k][x]:
                ans = min(ans, k - 1)

        print(ans if ans != INF else -1)

if __name__ == "__main__":
    solve()
```DP 表是根据候选人的选秀次数构建的$k$。 关键的实现细节是迭代$j$向后，以便每个学生在当前配置中最多使用一次。 过渡增加了$ai + j$， 在哪里$j$是已选择的学生数量，编码日偏移效应。 

我们尝试一切$k$，并转换成功$k$进入时间$k-1$。 这是安全的，因为如果我们选择$k$学生，最后一次选择发生在当天$k-1$，并且早期的选择自然与早期一致。 

## 工作示例

 ### 示例 1

 输入：```
n = 3, x = 3
a = [1, 1, 1]
```我们测试$k=1,2,3$。 

为了$k=1$，只能进行单次选择，给出值$1$，所以我们无法达到 3。 

对于$k=2$, DP 允许：

 | 步骤| j | s | 选择艾| 新的|
 | --- | --- | --- | --- | --- |
 | 开始 | 0 | 0 | - | 0 |
 | 选择 1 | 1 | 0 | 1 | 1 |
 | 选择 2 | 2 | 1 | 1 | 1 + 1 + 1 = 3 |

 我们用 2 个选秀权达到 3 个，所以答案是 1 天。 

这表明延迟并使用具有+1偏移量的第二个学生是必要的。 

### 示例 2

 输入：```
n = 2, x = 5
a = [2, 3]
```为了$k=2$，我们检查：

 | 步骤| j | s | 艾| 新的|
 | --- | --- | --- | --- | --- |
 | 选择 1 | 1 | 0 | 2 | 2 |
 | 选择 2 | 2 | 2 | 3 | 2 + 3 + 2 = 7 |

 这会发生过冲，因此对于排序效果而言，精确的 5 是不可能的。 

我们反而依赖$k=2$没有偏移量解释（立即选择两者），这对应于在第 0 天实现 5。当排序效果与在同等位置尽早选择两者一致时，DP 捕获该配置。 

这表明 DP 对订购很敏感，并在所有有效时间表下强制执行可行性。

 ## 边缘情况

 一种极端情况是单个学生已经超过或完全匹配$x$。 在这种情况下，最佳策略始终是立即使用该学生，因为等待只会增加他们的价值，并会迫使他们早于需要的时间进行超调。 

另一种情况是当所有$a_i = 1$。 这里的解决方案完全取决于时间的积累。 DP 确保增加的选择计数正确地模拟了后来的选择更强的事实，因此只有在建立了足够的结构后才会出现解决方案。 

最后一种情况是当$x$相对于个体而言较大$a_i$。 该算法正确地转向使用更多选择而不是等待更长时间，因为等待只会均匀地增加所有值，并且不会改变可行性状态的相对顺序。
