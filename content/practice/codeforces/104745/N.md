 ## 解决方案
 ## 问题理解

 我们得到一棵有根树，其节点编号为 1 到 n，以节点 1 为根。每个节点都带有不同的权重，这些权重形成从 1 到 n 的整数的排列。 

对于每个查询，我们关注特定的节点 u 和从 a 到 b 的整数区间。 任务是查看 u 的子树内部，并计算对于区间 [a, b] 中的每个整数 i，有多少个节点具有可被 i 整除的权重。 查询的最终答案是该间隔内所有 i 的所有计数的总和。 

因此，每个查询都要求进行双重聚合：首先在子树上进行聚合，然后在应用于节点权重的一系列除数上进行聚合。 

输入的结构意味着很大的限制。 测试用例中节点和查询的数量总计可达 200,000，这排除了任何针对每个查询重新计算子树信息的解决方案。 每个查询的简单遍历将导致 O(nq)，这远远超出了可行的限制。 即使显式维护每个子树的频率表也会超出内存或时间限制，因为每个查询的范围可能会很大的 i 间隔。 

一个微妙的边缘情况来自于基于除数的计数如何与树结构交互。 如果我们尝试独立地预先计算每个节点的贡献，我们会错过每个查询都将注意力限制在子树上。 如果我们尝试按查询进行 DFS，即使是平衡树也会退化为二次工作。 

## 方法

 直接的方法很简单：对于每个查询，遍历 u 的子树，对于其中的每个节点 v，迭代从 a 到 b 的所有 i 并检查是否 w[v] % i == 0。这是正确的，因为它实际上模拟了函数的定义。 然而，在最坏的情况下，每个子树遍历的成本为 O(n)，并且每个节点检查在时间间隔内的成本为 O(n)，导致在最坏的情况下每个查询的成本为 O(n²)。 对于多达 2e5 个查询，这是不可能的。 

关键的观察结果是权重是 1 到 n 的排列。 这使得除数关系结构化：每个值仅对其除数有贡献，并且这些除数受其大小的限制。 我们不考虑在 i 上扩展的查询，而是颠倒视角。 对于每个可能的除数 i，我们想知道对于任何子树，有多少个节点的权重是 i 的倍数。 这将问题转化为对于每个 i，维护其权重可被 i 整除的节点的频率。 

这建议通过按权重对节点进行分组并将它们的贡献传播到权重的所有除数来进行处理。 每个节点对所有 i 除 w[节点] 都有贡献。 如果我们可以将节点放入树的遍历顺序（例如欧拉遍历），那么每个子树就成为一个连续的段。 问题变成了对由除数索引的多个预先计算的频率数组进行一组范围和查询。 

然后，我们将其与标准离线策略结合起来：对于每个 i，我们在欧拉巡回索引上维护一个 BIT，标记其权重可被 i 整除的节点。 每个节点更新其所有除数。 每个查询都要求 BIT_i(subtree(u)) 从 a 到 b 的 i 总和。 这将问题简化为除数枚举加上子树范围查询。 

由于每个数字大约有 O(sqrt(n)) 个除数，因此总更新量是可控的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²q) | O(1) | O(1) | 太慢了 |
 | 最佳 | O((n + q + 总和 d(w)) log n) | O(n + n log n) | O(n + n log n) | 已接受 |

 ## 算法演练

 ### 第 1 步：使用欧拉之旅压平树

 我们从根运行 DFS，并为每个节点分配进入时间和退出时间。 任何节点 u 的子树都成为欧拉阶中的连续段 [tin[u], tout[u]]。 这种转换允许将子树查询简化为范围查询。

### 步骤 2：预先计算所有值的除数

 对于从 1 到 n 的每个值，我们计算其除数列表。 这是必需的，因为每个节点不仅对自身有贡献，而且对划分其权重的所有除数索引 i 都有贡献。 

这是有效的原因是，对于固定的 i，当节点的权重是 i 的倍数时（相当于 i 是权重的除数），节点就会做出贡献。 

### 步骤 3：构建按除数分组的 BIT

 我们在欧拉游览位置上为每个可能的 i 维护一棵 Fenwick 树。 从概念上讲，BIT[i] 跟踪欧拉阶中哪些节点的权重可被 i 整除。 

对于每个节点 v，我们迭代 w[v] 的所有除数 d，并将位置tin[v] 处的 BIT[d] 更新 +1。 这确保了 BIT[d] 准确存储了权重为 d 倍数的所有节点。 

### 步骤 4：回答按除数分组的查询

 每个查询都要求除数范围 [a, b]。 对于这个范围内的每个 i，我们在子树段 [tin[u], tout[u]] 上查询 BIT[i] 并累加结果。 

尽管天真地对每个查询进行迭代看起来很昂贵，但所有查询的总和以 2e5 为界，因此我们依赖于 Fenwick 查询的直接迭​​代。 

### 步骤 5：有效聚合结果

 我们增量计算答案，确保每个 BIT 查询都是 O(log n)。 由于每个节点都贡献一个小的除数集，因此预处理仍然有效。 

### 为什么它有效

 核心不变量是，对于每个除数 i，BIT[i] 始终准确地表示权重可被 i 整除的节点集，并在欧拉位置上进行编码。 由于子树查询对应于欧拉顺序的连续段，因此对子树内的有效节点进行计数可减少为 BIT[i] 中的前缀和差。 每个查询只是将一定范围内的这些独立除数计数相加，因此线性保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        w = list(map(int, input().split()))

        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)

        tin = [0] * n
        tout = [0] * n
        euler = []
        timer = 0

        stack = [(0, -1, 0)]
        while stack:
            u, p, state = stack.pop()
            if state == 0:
                tin[u] = len(euler) + 1
                euler.append(u)
                stack.append((u, p, 1))
                for v in g[u]:
                    if v != p:
                        stack.append((v, u, 0))
            else:
                tout[u] = len(euler)

        bits = [None] * (n + 1)
        for i in range(1, n + 1):
            bits[i] = BIT(n)

        def divisors(x):
            ds = []
            i = 1
            while i * i <= x:
                if x % i == 0:
                    ds.append(i)
                    if i * i != x:
                        ds.append(x // i)
                i += 1
            return ds

        for v in range(n):
            for d in divisors(w[v]):
                bits[d].add(tin[v], 1)

        for _ in range(q):
            u, a, b = map(int, input().split())
            u -= 1
            res = 0
            l, r = tin[u], tout[u]
            for i in range(a, b + 1):
                res += bits[i].range_sum(l, r)
            print(res, end=" ")
        print()

if __name__ == "__main__":
    solve()
```该实现首先压平树，使子树查询变成区间查询。 Fenwick 树结构用于维护欧拉排序中每个除数的计数。 每个节点都被插入到与其权重除数相对应的所有 BIT 中。 

查询循环直接在区间 [a, b] 上迭代，对子树范围内每个除数 BIT 的结果求和。 主要的微妙之处在于，tin/tout 是根据欧拉阶定义的，因此可以正确捕获子树成员资格。 

一个仔细的细节是，我们使用迭代DFS来避免递归深度问题，因为n可以达到2e5。 另一个是 BIT 索引是从 1 开始的，这与锡索引相匹配。 

## 工作示例

 考虑一棵小树，其中节点 1 是根节点，子节点为 2 和 3，权重为 [1, 2, 3]。 假设我们查询范围为 [1, 2] 的节点 1。 

对于 i = 1，所有权重均可被 1 整除，因此子树计数为 3。对于 i = 2，只有节点 2 符合条件，因此计数为 1。总计为 4。 

| 步骤| 节点已处理 | 重量 | 除数 | 双边投资协定更新 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 | 位[1][1] += 1 |
 | 2 | 2 | 2 | 1,2 | 位[1][2] += 1，位[2][2] += 1 |
 | 3 | 3 | 3 | 1,3 | 位[1][3] += 1，位[3][3] += 1 |

 对子树 [1,3] 的查询在 BIT[1] 和 BIT[2] 上正确聚合，产生 4。 

这证实了除数传播到 BIT 层中保留了子树间隔上的正确聚合。

 ## 边缘情况

 关键的边缘情况是当子树是整个树并且查询间隔跨越整个除数范围时。 在这种情况下，每个 BIT[i] 都会在整个欧拉段上查询，因此答案简化为计算权重为每个 i 倍数的所有节点。 该算法正确地处理了这个问题，因为每个节点都会对其全局的所有除数做出贡献。 

当节点具有素数权重时，会出现另一种边缘情况。 这样的节点仅对 1 及其自身做出贡献，这意味着它更新的 BIT 很少。 该算法仍然表现正确，因为除数枚举自然地处理素数而无需特殊的大小写。 

最后的边缘情况是深度为 n 的退化树。 欧拉区间仍然保持有效的连续段，因此即使递归结构完全线性，子树查询也保持正确。
