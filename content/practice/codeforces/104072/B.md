 ## 解决方案
 ## 问题理解

 我们得到一条线，其中有几个球放置在不同的位置。 每个球从已知坐标开始，沿着数轴以恒定速度向左或向右移动。 所有球同时开始移动。 不同的是，每当两个球相遇时，它们不会以复杂的物理方式相互作用，而是通过交换速度来相互穿过，如果我们忽略身份，这使得系统相当于自由移动的粒子。 

在固定时间 T，我们被要求确定所有球的位置。 最终输出与原始身份无关，因为碰撞有效地改变了球之间的速度。 相反，我们感兴趣的是时间 T 之后所有球的位置的多重集，以非降序打印。 

关键约束是 N 最大为 100000，坐标和速度的大小最大为 10^9，时间最大为 10^9。 这立即意味着任何逐步推进时间或明确处理碰撞的模拟都是不可能的。 在最坏的情况下，简单的碰撞模拟需要处理潜在的 O(N^2) 交互事件，因为每对球都可以通过交换链间接交互。 即使是事件驱动的模拟也会太慢，因为碰撞事件的数量可能是二次的。 

当多个球共享相同的初始位置或由于速度不同而同时到达同一点时，会出现一种更简单但微妙的边缘情况。 由于碰撞被定义为瞬时交换，因此这些情况不会在最终位置集中产生歧义，但它们破坏了尝试显式模拟排序而不是使用运动的数学变换的简单实现。 

例如，考虑位置 0 和 10 处的两个球以速度 1 和 -1 相向移动。 T = 5 后，它们在位置 5 处碰撞并交换速度，因此左侧的球在右侧结束，反之亦然。 幼稚的模拟跟踪身份将被迫精确处理碰撞顺序，但最终位置与球相互穿过一样。 

核心建模见解是，碰撞时交换速度使系统相当于让球在没有相互作用的情况下相互穿过，然后根据顺序重新分配身份。 

## 方法

 暴力视图是模拟运动并显式处理碰撞。 我们将维护所有球按位置排序，重复查找下一个碰撞事件，提前到该事件的时间，交换碰撞对的速度，一直持续到时间 T。每次碰撞都是一个事件，在最坏的情况下，每对相邻的球都可以根据速度碰撞多次。 事件的数量可以达到 O(N^2)，并且每个事件都需要优先级队列更新或列表扫描，使得解决方案对于 N = 100000 来说太慢。 

关键的观察结果是，在碰撞过程中交换速度相当于说，如果我们忽略球的身份，它们的行为就好像它们没有改变地穿过彼此一样。 这意味着我们可以计算每个球独立移动时的位置：时间 T 的位置就是 p_i + s_i * T。 

唯一剩下的问题是冲突交换身份，但由于输出只需要按非降序排序的位置，因此身份无关紧要。 独立计算所有最终位置后，对它们进行排序给出正确的配置。 半径 R 与最终位置无关，因为它仅在发生碰撞时产生影响，而不是轨迹交换的数学等价物。 

因此，问题简化为计算每个球的线性变换并对结果进行排序。

 | 暴力模拟| O(N^2) 或更糟 | O(N) | 太慢了 |

 ## 算法演练

 1. 对于每个球，计算其位置，就好像从未发生过碰撞一样。 这是使用 p_i + s_i * T 完成的，它表示恒定速度下的匀速运动。 此步骤是有效的，因为碰撞仅交换速度并且不会改变轨迹集。 
2. 将所有计算出的位置存储在数组中。 此时，每个条目代表某个球的最终可能位置，但身份不再有意义。 
3. 按非降序对位置数组进行排序。 排序是必要的，因为碰撞只会排列哪个球占据哪个轨迹，但最终坐标集不会改变。 
4. 输出排序后的列表作为最终配置。 

为什么它有效

 关键的不变量是碰撞只会改变球之间的速度，这意味着多组轨迹被保留。 如果我们想象将每个速度标记为一个令牌并让它自由移动，则每个令牌都会遵循一条直线路径。 交换机制确保球在相遇时简单地交换这些代币。 因此，在任意时刻T，小球所占据的位置集合正是在不考虑碰撞的情况下，每个初始小球独立前进所得到的位置集合。 唯一的区别是哪个球最终到达哪个位置，这是无关紧要的，因为输出是排序的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, r, t = map(int, input().split())
    pos = []
    
    for _ in range(n):
        p, s = map(int, input().split())
        pos.append(p + s * t)
    
    pos.sort()
    print(*pos)

if __name__ == "__main__":
    solve()
```该实现直接遵循碰撞不影响最终位置的多重集的观察。 每个球的轨迹都是独立计算的，然后对结果进行排序。 

唯一微妙的一点是使用 64 位安全算术。 在 Python 中这是自动的，但在其他语言中需要小心，因为 p_i 和 s_i * T 最多可达 10^18。

 ## 边缘情况

 一种微妙的情况是两个球最终位于完全相同的计算位置。 例如，从不同点开始的两个球可以由于相反的速度在时间 T 后落在同一坐标上。 该算法仍然有效，因为排序自然地处理相等的值，并且原始过程中的碰撞也允许临时重叠而不改变最终位置集。 

另一种边缘情况是 T = 0。在这种情况下，计算的位置减少到初始位置 p_i，并且排序只是按坐标返回初始排序，这符合要求，因为没有发生运动。 

进一步的边缘情况是负速度与大 T 相结合，这会将位置推至负数。 公式 p_i + s_i * T 直接处理这个问题，Python 整数算术可以防止固定宽度整数语言中出现的溢出问题。
