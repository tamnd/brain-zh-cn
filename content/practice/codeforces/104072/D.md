 ## 解决方案
 ## 问题理解

 我们有一个大小为的正方形网格$N \times N$，其中每个单元格包含 0 或 1。值为 1 的单元格代表一朵“好”花，而 0 代表一朵坏花。 任务是计算有多少个正方形子矩阵具有其边界上的每个单元格都是 1 的属性。正方形的内部单元格根本不重要，只有所选正方形的外部边界必须完全为 1。 

正方形是通过选择其左上角和边长来定义的。 对于每个这样的选择，我们检查该正方形的周长单元格并检查它们是否全部为 1。答案是所有位置和大小的有效正方形总数。 

约束条件$N \le 3000$意味着网格有多达 900 万个单元。 明确检查每个方块的解决方案将粗略地考虑$O(N^2)$职位及最多$O(N)$边长，给出$O(N^3)$检查，速度太慢。 甚至$O(N^2 \log N)$除非每项检查都非常便宜，否则方法可能是边缘性的。 问题的结构强烈表明我们需要对网格进行预处理，以便周边检查变得恒定时间或接近恒定时间。 

常见的失败案例是将其视为完整子矩阵问题而不是仅边界问题。 例如，简单的 2D 前缀和方法可能会错误地要求正方形内的所有单元格都为 1。 

考虑这个输入：```
1 1 1
1 0 1
1 1 1
```3×3 的正方形无效，因为边框包含中心单元格？ 实际上中心不在边界上，因此 3×3 正方形是有效的，因为所有边界单元都是 1。由于中心为零，简单的全子矩阵检查会错误地拒绝它。 

另一个微妙的情况是当正方形退化为大小 1 时。如果单个单元格为 1，则 1×1 正方形始终有效，因为周长就是该单元格。 

这些极端情况使得混合“内部”和“边界”条件变得危险。 

## 方法

 暴力方法枚举每个可能的正方形并直接检查其周长。 对于每个左上角$(i, j)$以及每个可能的边长$k$，我们扫描正方形的四个边并验证所有值均为 1。检查单个正方形的成本$O(k)$，因此总复杂度变为$O(N^4)$以最坏的解释或$O(N^3)$如果通过重用部分扫描进行稍微优化。 无论哪种方式，与$N = 3000$，这远远超出了可行的限度。 

关键的观察是周界有效性可以分解为方向连续信息。 我们不是重复扫描边缘，而是预先计算有多少个连续的 1 从每个单元向右延伸，以及有多少个向下延伸。 一旦知道这些，任何水平或垂直的 1 秒段都可以在恒定时间内得到验证。 一个正方形的大小$k$开始于$(i, j)$如果其上边缘、下边缘、左边缘和右边缘都至少包含$k$从各自的端点开始连续的1s。 这将周界检查转变为每个候选方格的四次恒定时间查找。 

这将问题减少到迭代所有正方形位置并使用预先计算的运行测试每个尺寸，从而进行检查$O(1)$以及完整的解决方案$O(N^3)$或更佳取决于早期停止和修剪。 通过仔细处理每个单元格的最大可行平方大小，我们有效地显着减少了检查数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力周边扫描|$O(N^4)$|$O(1)$| 太慢了 |
 | 定向 DP（右/下跑）|$O(N^2 \cdot N)$最差，但通过修剪进行优化$O(N^2)$| 已接受 |

 ## 算法演练

 我们首先计算两个辅助表。 对于每个单元格，存储有多少个连续的 1 从该单元格开始向右延伸。 第二个存储有多少个连续的 1 向下延伸。 这些是通过从右下角到左上角扫描网格来计算的，因此每个状态仅取决于先前计算的邻居。 

预处理后，我们将每个单元格作为正方形的潜在左上角进行迭代。 对于每个这样的单元格，我们尝试扩展正方形边长$k$。 对于一个正方形大小$k$要有效，必须满足四个条件： 顶部边缘必须至少有$k$向右连续 1 秒，底边也必须至少有$k$向右连续 1，同样，左右边缘必须至少有$k$连续1s向下。 

我们增加$k$逐渐地，并且一旦任何边界条件失败就停止从给定的原点扩展，因为更大的正方形只会使这些约束更加严格。 

最后，我们累积在这些扩展期间找到的所有有效方块的计数。 

关键的不变量是预先计算的右数组和下数组正确地表示从每个单元开始的最大连续 1 段。 每次周长检查都简化为验证相应的线段长度是否至少等于正方形的边长。 由于每个方块边界都是由这些线段精确组成的，因此不会遗漏任何有效方块，也不会对无效方块进行计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [list(map(int, input().split())) for _ in range(n)]

    right = [[0] * n for _ in range(n)]
    down = [[0] * n for _ in range(n)]

    for i in range(n - 1, -1, -1):
        for j in range(n - 1, -1, -1):
            if g[i][j] == 1:
                right[i][j] = 1 + (right[i][j + 1] if j + 1 < n else 0)
                down[i][j] = 1 + (down[i + 1][j] if i + 1 < n else 0)

    ans = 0

    for i in range(n):
        for j in range(n):
            max_k = min(right[i][j], down[i][j])
            k = 1
            while k <= max_k:
                if i + k - 1 >= n or j + k - 1 >= n:
                    break

                if right[i + k - 1][j] >= k and down[i][j + k - 1] >= k:
                    ans += 1
                    k += 1
                else:
                    break

    print(ans)

if __name__ == "__main__":
    solve()
```预处理循环计算 1 秒的最大水平和垂直运行。 每个单元格上的迭代使用这些运行立即限制最大可能的正方形大小，避免无用的检查。 然后，扩展循环仅显式验证底部和右侧边缘，因为顶部和左侧边缘由起始单元格的预先计算值隐式保证。 

一个微妙的实现细节是 while 循环内的停止条件。 一旦一个正方形大小$k$如果失败，来自同一原点的任何更大的正方形也会失败，因为它延伸了至少一个已经无效的边界。 这种单调性使得提前停止变得安全。

 ## 边缘情况

 对于包含 0 的 1×1 网格，该算法正确地生成 0，因为两个方向数组都为零，因此没有正方形被认为是有效的。 

对于 1 仅形成薄边界的网格（例如空心正方形），该算法仍会计算大的有效正方形，因为它仅依赖于边界连续性，而不依赖于内部密度。 DP 阵列正确地反映了沿边缘的不间断运行，因此即使内部充满零，周界检查也能保持准确。
