 ## 解决方案
 ## 问题理解

 我们有两个对象集合。 一组包含螺母，另一组包含螺栓。 每个螺母都有独特的尺寸，每个螺栓都有独特的尺寸，并且尺寸形成相同的范围。 了解两个集合之间关系的唯一方法是比较一个螺母和一个螺栓。 通过比较，我们可以知道螺母与螺栓的尺寸是更小、更大还是完全相同。 

目标是为每个螺母找到具有相同尺寸的螺栓的索引。 该程序不直接接收尺寸。 相反，它必须进行比较并使用答案来重建隐藏的匹配。 

的极限为`5 * n * log2(n)`比较告诉我们，尝试所有可能的螺母和螺栓对是不可行的。 和`n = 1000`，二次方法将进行大约一百万次比较，而允许的比较次数只有大约五万次。 该解决方案必须重复删除大部分搜索空间，这指向类似于快速排序的分而治之的方法。 

棘手的情况是由于两个组没有排序并且只允许跨组比较而造成的。 粗心的解决方案可能会通过相互比较坚果来对坚果进行分类，但这种比较是不可能的。 例如，有两个螺母和两个螺栓，其中隐藏顺序是螺母尺寸`[2, 1]`和螺栓尺寸`[1, 2]`，正确答案是坚果`1`火柴螺栓`2`和坚果`2`火柴螺栓`1`。 尝试对螺母和螺栓进行独立排序的方法无法执行所需的比较。 

另一个失败情况是忘记分区必须在两侧使用相同的主元信息。 假设选定的螺母与螺栓阵列中间的某个螺栓相匹配。 找到该螺栓后，必须通过与该确切螺栓的比较来划分剩余的螺母。 如果实现选择不同的螺栓作为枢轴，则两个分区可能不再描述相同的大小范围，并且可能会丢失有效的匹配。 

## 方法

 直接的解决方案是将每个螺母与每个螺栓进行比较，直到找到所有匹配项。 由于每个螺母都有一个匹配的螺栓，因此最终成功了。 最坏的情况需要`n * n`比较，因为匹配的螺栓始终可能是每个螺母测试的最终螺栓。 为了`n = 1000`，这是一百万次比较，远远超出了要求的范围。 

关键的观察结果是，比较不仅仅提供了可能的匹配。 它还提供订购信息。 如果将螺母与螺栓进行比较，并且螺母较小，则该螺母无法与任何大于或等于该螺栓的螺栓匹配。 如果更大，则适用相反的限制。 

这允许我们使用快速排序式分区。 选择一个螺母作为枢轴，并将其与每个螺栓进行比较。 这将螺栓分为较小的螺栓、一个匹配的螺栓和较大的螺栓。 现在已知匹配的螺栓。 接下来，使用该螺栓将剩余的螺母分成相同的两个尺寸组。 左组螺母只能匹配左组螺栓，右组只能匹配右组螺栓。 然后可以递归地重复相同的过程。 

比较次数遵循与快速排序相同的模式。 每级递归都会处理所有剩余元素，当枢轴合理分割组时，深度为对数。 比较限制对于标准随机版本有足够的余量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳| 预期 O(n log n) | O(log n) | 已接受 |

 ## 算法演练

 1. 从当前系列中选择一个螺母作为枢轴。 将其与当前螺栓系列中的每个螺栓进行比较。 存储给出相等答案的螺栓。 这些比较还将所有其他螺栓分为小于枢轴螺母的螺栓和大于枢轴螺母的螺栓。 

枢轴螺母的匹配螺栓现已固定，因为没有其他螺栓可以具有相同的尺寸。 

1. 将当前螺母系列中的所有其他螺母与上一步中找到的匹配螺栓进行比较。 将较小的坚果放入左侧组，将较大的坚果放入右侧组。 

使用配套螺栓作为分隔件，使螺母分区和螺栓分区保持一致。 左侧螺母组只能匹配左侧螺栓组，右侧遵循同样的规则。 

1. 保存发现的枢轴螺母及其螺栓对。 
2. 递归求解左侧螺母和螺栓组，然后递归求解右侧螺母和螺栓组。 空群和单元素群已经解决。 
3. 所有递归调用完成后，输出每个螺母索引所存储的螺栓索引。 

为什么它有效：

 不变的是，每个递归调用都会接收两组包含完全相同的尺寸集，一组由螺母表示，一组由螺栓表示。 当将枢轴螺母与所有螺栓进行比较时，恰好有一个螺栓与其匹配，并且每个其他螺栓都相对于该尺寸进行分类。 将螺母与匹配的螺栓进行比较，会在螺母侧产生相同的裂缝。 由于每个可能的匹配都保留在一个递归子问题内，并且枢轴匹配会被永久记录，因此每个螺母都会收到正确的螺栓。 

## Python 解决方案```python
import sys
import random

input = sys.stdin.readline

def solve():
    n = int(input())
    ans = [0] * n

    def ask(nut, bolt):
        print("?", nut + 1, bolt + 1, flush=True)
        return input().strip()

    def divide(nuts, bolts):
        if not nuts:
            return

        if len(nuts) == 1:
            ans[nuts[0]] = bolts[0]
            return

        pivot_nut = nuts[random.randrange(len(nuts))]

        smaller_bolts = []
        larger_bolts = []
        pivot_bolt = -1

        for bolt in bolts:
            res = ask(pivot_nut, bolt)
            if res == "<":
                larger_bolts.append(bolt)
            elif res == ">":
                smaller_bolts.append(bolt)
            else:
                pivot_bolt = bolt

        smaller_nuts = []
        larger_nuts = []

        for nut in nuts:
            if nut == pivot_nut:
                continue
            res = ask(nut, pivot_bolt)
            if res == "<":
                smaller_nuts.append(nut)
            else:
                larger_nuts.append(nut)

        ans[pivot_nut] = pivot_bolt

        divide(smaller_nuts, smaller_bolts)
        divide(larger_nuts, larger_bolts)

    divide(list(range(n)), list(range(n)))

    print("!", *[x + 1 for x in ans], flush=True)

if __name__ == "__main__":
    solve()
```递归函数保留两个代表当前未解决的具体细节的并行数组。 基本情况处理空范围和一个剩余的对，其中答案已经是强制的。 

主元选择是随机的，因为固定主元可以重复选择最小或最大元素并创建递归深度`n`。 随机选择给出了比较限制所需的预期平衡行为。 

第一个分区仅将枢轴螺母与螺栓进行比较。 第二个分区仅将螺母与已发现的枢轴螺栓进行比较。 这些操作的顺序很重要，因为枢轴螺栓是将信息从螺栓侧传输回螺母侧的桥梁。 

答案数组在内部使用从零开始的索引来存储螺栓索引。 最终输出将它们转换回交互协议所需的基于一的索引。 

## 工作示例

 考虑一个小的隐藏排列，其中螺母索引对应于尺寸`[3, 1, 2]`螺栓索引对应于尺寸`[2, 3, 1]`。 

第一个枢轴选择可能会选择螺母`1`，其大小为`3`。 

| 步骤| 枢轴螺母| 比较螺栓| 结果 | 状态|
 | ---| ---| ---| ---| ---|
 | 1 | 坚果 1 | 螺栓 1 | 坚果较大| 螺栓 1 向左移动 |
 | 2 | 坚果 1 | 螺栓 2 | 等于| 螺栓 2 匹配 |
 | 3 | 坚果 1 | 螺栓 3 | 坚果较大| 螺栓 3 向左移动 |

 枢轴匹配存储为螺母`1`螺栓`2`。 剩下的螺母通过与螺栓对比来拆分`2`。 

| 步骤| 对比坚果| 相对于枢轴螺栓的结果 | 集团|
 | ---| ---| ---| ---|
 | 1 | 坚果 2 | 较小| 左|
 | 2 | 坚果 3 | 较小| 左|

 递归调用处理剩余的两对。 该迹线证明了中心不变量：两个集合都围绕相同大小的边界进行划分。 

对于具有五个元素的样本，算法重复执行相同的过程。 可能的第一个分区会发现一个精确的对，然后将剩余的四对分成两个较小的独立问题。 每个递归层都无需再次比较不相关的大小。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 预期 O(n log n) | 每个递归级别都会比较所有剩余元素，随机枢轴给出对数预期深度 |
 | 空间| 预期 O(log n) | 递归堆栈每个划分级别存储一帧 |

 最大`n`足够小，以至于预期`O(n log n)`比较次数正好适合`5 * n * log2(n)`。 内存占用也很小，因为只存储递归栈和临时分区。

 ## 边缘情况

 剩下的一对是最小的递归状态。 对于带有一个尺寸的螺母的情况`1`和一个尺寸的螺栓`1`，该算法从不执行不必要的分区并直接记录唯一可能的匹配。 

反向排序测试两个分区是否保持同步。 适用于尺寸的螺母`[2, 1]`和螺栓尺寸`[1, 2]`，选择第一个螺母作为枢轴查找螺栓`2`作为它的匹配。 另一个螺母和螺栓在分区的另一侧保持在一起，因此递归调用正确分配螺栓`1`。 

高度不平衡的序列是主要的性能危险。 如果实现始终选择第一个螺母作为枢轴并且数据已经排序，则递归可能会降级为线性深度。 随机主元避免依赖于原始排序，并将预期的比较数量保持在所需的范围内。
