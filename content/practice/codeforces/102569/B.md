 ## 解决方案
 ## 问题理解

 我们在数轴上放置了一组奖励位置。 起始位置为坐标0，移动一单位距离总是消耗一秒。 任务是选择一组奖金并在可用时间内访问每个选定的地点`t`。 答案是可以收集到的最大奖金数量，而不是行驶的距离或最终的位置。 

输入给出了奖金的数量、时间限制以及所有奖金的已排序坐标。 由于坐标已排序，因此附近的奖励会彼此相邻存储，这是允许有效解决方案的结构属性。 输出是一个整数，表示可以达到的最大奖金数。 

奖金数量可以达到200000，因此检查每组可能的奖金是不现实的。 在最坏的情况下，二次算法将执行大约 40000000000 次操作，这远远超出了 2 秒所允许的限制。 我们需要一种接近线性时间的方法。 坐标和时间限制可以大到`10^9`，因此计算必须使用可以安全存储较大中间值的整数算术。 Python 整数已经处理了这个问题。 

一个常见的错误是只检查所选范围内最远奖励的距离。 当所有奖励都在原点的一侧时，这种方法有效，但当奖励同时存在于原点的一侧时，这种方法会失败，因为返回原点需要额外的移动。 例如，与：```
3 4
-2 1 3
```正确答案是`2`。 参观`-2`和`1`成本`2 + 3 = 5`如果我们先向左走，则秒，或者`1 + 3 = 4`如果我们先向右走，则需要几秒钟，因此可能有两个奖励。 仅查看最远坐标的方法会错误地认为所有三个奖励都适合，因为最远坐标是`3`。 

另一个边缘情况是没有时间。 例如：```
1 0
5
```正确的输出是`0`。 从一项可达到的奖金开始或在移动之前检查位置的粗心实施可能会错误地计算它。 

第三种情况是最佳范围过零但开始和结束于相反的两侧。 例如：```
4 5
-4 -1 2 10
```最好的选择是`-1, 2`，这需要`3`如果我们先向右走的话几秒钟。 包括`-4`需要更多的时间。 总是扩展到最大可能的坐标范围而不考虑回程的算法会高估答案。 

## 方法

 直接的暴力解决方案将尝试每一个可能的连续奖金部分。 对于每个路段，我们可以计算从零开始并访问路段两端的最短路线。 由于段内的所有奖励都位于这两个端点之间，因此访问端点就足够了。 这是正确的，因为一旦我们达到两个极端，所有中间奖金都可以在途中收集。 

问题在于段的数量。 有大约`n * (n + 1) / 2`可能的段，大约为20000000000`n = 200000`。 即使进行恒定时间成本检查，这也太慢了。 

关键的观察是，最佳的一组奖金始终是排序数组中的连续段。 如果解决方案采用两个奖励并跳过它们之间的奖励，则添加跳过的奖励不会花费额外的移动，因为路线已经经过其位置。 这就把问题变成了寻找最长的有效窗口。 

对于固定的右端点，将左端点向右移动只能使所需的行进距离变小或保持不变。 这种单调行为允许使用两指针方法。 我们一次向右侧提供一项奖励，每当当前窗口需要超过`t`几秒钟后，我们从左侧删除奖励，直到窗口再次成为可能。 

窗户的行程成本仅取决于其两端。 如果整个窗口都在正侧，则成本是最右边的坐标。 如果在负数一侧，成本就是最左边坐标的绝对值。 如果它过零，则有两种可能的顺序：先访问左侧或先访问右侧。 我们取两者中较小的一个。

 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 保留两个描述当前奖金段的指针。 右侧指针从左向右展开，每次增加一个新的奖励。 左指针标记当前包含的第一个奖金。 
2. 添加新的右端点后，计算访问当前路段所需的最短时间。 唯一需要的坐标是最左边和最右边的奖金，因为所有其他奖金都位于它们之间。 
3. 如果当前段需要多于`t`秒，将左指针向右移动一位并再次检查。 从左边删除奖励并不能增加所需的时间，因此这个过程最终会找到以当前右指针结尾的最长有效段。 
4. 只要当前段有效，就用其大小更新答案。 扫描期间看到的最大尺寸是可以收集的最大奖金数量。 

不变的是，收缩后，当前窗口始终是以当前右端点结束的最长有效窗口。 任何具有相同右端点但左端点较小的窗口都已被检查，如果被删除则无效。 由于考虑了每个可能的右端点，因此扫描找到的最大有效窗口是全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, t = map(int, input().split())
    x = list(map(int, input().split()))

    def cost(l, r):
        left = x[l]
        right = x[r]

        if right <= 0:
            return -left
        if left >= 0:
            return right

        return min(right - 2 * left, 2 * right - left)

    ans = 0
    l = 0

    for r in range(n):
        while l <= r and cost(l, r) > t:
            l += 1
        if l <= r:
            ans = max(ans, r - l + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```这`cost`功能是解决方案的核心。 当两端均为负值时，最远点在左侧，所需的移动只是从零到左端点的距离。 当两端均为正值时，右端点决定成本。 当线段过零时，两个公式代表访问边的两种可能的顺序。 

主循环遵循两个指针过程。 右指针仅向前移动一次，左指针也仅向前移动一次，因此指针移动的总数是线性的。 反复的呼吁`cost`仅使用一些算术运算。 

收缩环中的边界条件很重要。 如果检查其成本，仅包含当前右端点的窗口仍然有效，因此条件允许`l == r`。 如果每项奖金都离得太远，窗口就会变成空的，答案仍然为零。 

不需要对大坐标进行特殊处理，因为 Python 整数不会溢出。 在具有固定大小整数类型的语言中，涉及双倍坐标的表达式需要 64 位整数。

 ## 边缘情况

 对于零时间情况：```
1 0
5
```右边的指针从唯一的奖金开始。 成本是`5`，大于`t`，因此左指针移过右指针。 窗口变空，答案保持为零。 该算法从不计算无法达到的奖金。 

对于两侧为零的范围：```
3 4
-2 1 3
```包含所有三个奖金的窗口有成本`2 * 3 - (-2) = 8`或者`3 - 2 * (-2) = 7`，所以被拒绝。 左指针移动直到窗口`[-2, 1]`剩下的，其成本为`1 - 2 * (-2) = 5`和`2 * 1 - (-2) = 4`，给出有效成本`4`。 答案变成了两个。 

对于完全位于一侧的窗户：```
3 5
-6 -3 -1
```该算法不使用过零公式。 成本只是到最远负点的距离。 第一个窗口有成本`6`，因此左指针移动。 剩余奖金`-3, -1`成本`3`秒并被计数，产生输出`2`。 

对于大坐标：```
2 2000000000
-1000000000 1000000000
```交叉公式计算周围的值`3000000000`，超出了 32 位整数限制。 Python 可以正确处理这个问题，算法会比较完整的整数值，然后决定两个奖金是否合适。 输出是`2`。
