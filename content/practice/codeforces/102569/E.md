 ## 解决方案
 # 问题理解

 旅程包括按固定顺序访问魔法源泉。 每个源都会改变法师当前的法力一定量，唯一的失败条件是法力水平随时降至零以下。 任务是确定允许法师在整个序列中生存的最小起始法力值。 

输入数组描述了源引起的法力变化。 正值会增加当前法力值，负值会消耗法力值，零值则使其保持不变。 输出不是旅程结束后的最终法力，而是所需的最小初始量，以便旅程的每个前缀都保持法力非负。 

最多 500000 个源的约束意味着解决方案必须在线性时间内处理阵列。 尝试许多可能的起始值或重复模拟旅程的方法会执行太多操作。 在 2 秒限制下，预计算法约为 O(n) 或 O(n log n)，而 O(n²) 方法远远超出了可行范围。 

有些情况通常会破坏错误的解决方案。 仅包含积极变化的序列的答案为零，因为法师永远不会失去法力。 例如：```
3
5 2 8
```正确的输出是：```
0
```假设总是需要一些积极的起始法力的解决方案在这里会失败。 

在考虑后来的正值之前，必须先处理开始时的大负值。 例如：```
3
-10 20 -5
```正确的输出是：```
10
```第一个来源立即需要至少 10 点法力。 如果粗心地只查看最终总和，整个旅程将获得 5 点法力值，并且可能会错误地回答零。 

另一个微妙的情况是，最严重的赤字发生在中间而不是最后。 例如：```
5
4 -7 1 1 10
```正确的输出是：```
3
```在前两个来源之后，总变化为 -3，因此需要三个起始法力。 仅查看总和（即 9）会错过暂时的下降。 

# 方法

 直接的做法是猜测初始法力并模拟旅程。 对于固定的起始值，检查法师是否幸存需要 O(n) 时间，因为每个源都必须访问一次。 我们可以从零开始尝试所有可能的起始值，直到有一个有效为止。 由于答案可能与许多负面变化的总和一样大，因此在最坏的情况下可能需要大约 500000 × 10^9 操作，这是不可能的。 

对答案的二分搜索改进了这个想法。 该条件是单调的：如果起始法力值起作用，则任何更大的值也起作用。 这给出了 O(n log A) 方法，其中 A 是可能答案范围的大小。 然而，问题的结构允许更简单的观察。 

不要反复询问所选的起始值是否足够，而是跟踪法力变化本身。 想象一下从零法力开始并跟踪整个旅程。 在每一点上，运行总和都会告诉我们法师的跌落幅度会低于零多少。 低于零的最大跌幅正是一开始缺失的法力值。 添加缺失的数量会将每个前缀向上移动到足以使最小前缀等于零。 

例如，如果运行总计为：```
3, -1, 1, -2, -4, 3
```最低值为-4。 从 4 点法力开始，总计将达到：```
7, 3, 5, 2, 0, 7
```现在每个值都是有效的，任何较小的起始金额仍然会使最低点为负值。 

蛮力之所以有效，是因为它测试起始值是否保护旅程的每个前缀，但它会多次重复相同的模拟。 只有最小前缀和才重要的观察结果让我们可以一次性找到答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n × 答案) | O(1) | O(1) | 太慢了|
 | 最佳| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从运行的法力余额为零开始，并用一个变量存储迄今为止达到的最小余额。 运行平衡代表如果法师以零法力开始会发生什么。 
2. 按顺序处理每个法力变化并将其添加到运行余额中。 每次添加后，如果当前值较小，则更新最小余额。 
3. 整个序列处理完毕后，如果最小余额为负，则返回其绝对值。 如果最小余额为零或正数，则返回零。 

最小前缀就足够的原因是，每个危险时刻都发生在处理完数组的某个前缀之后。 所需的最大初始法力值正是将最低前缀恢复为零所需的量。 

为什么有效：运行总和描述了法师在零法力开始时可能死亡的所有可能点。 假设最小运行总和是`-x`。 任何小于以下的起始法力值`x`会使该点低于零，所以至少`x`法力是必要的。 完全从`x`将每个运行总和增加`x`，使最小值为零且所有其他值非负。 因此`x`既是必要的又是充分的。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n_line = input().strip()
    if not n_line:
        return

    n = int(n_line)
    a = list(map(int, input().split()))

    current = 0
    minimum = 0

    for value in a:
        current += value
        if current < minimum:
            minimum = current

    print(-minimum)

if __name__ == "__main__":
    solve()
```该代码在扫描数组时仅保留两条信息。`current`是虚拟模拟中法师从零法力开始的法力水平。`minimum`存储该模拟达到的最低值。 

每当运行平衡变小时，就意味着法师需要额外的起始法力才能生存下去。 最终的答案是最低余额的负数。 自从`minimum`从零开始，永远不会变负的序列会自动产生答案零。 

Python 整数不会溢出，这一点很重要，因为 500000 个大小高达 10^9 的值的总和可以达到大约 5 × 10^14。 该算法还避免存储不必要的前缀和，保持内存使用恒定。 

# 工作示例

 对于示例输入：```
6
3 -4 2 -3 -2 7
```痕迹是：

 | 来源价值| 当前余额| 最低余额 |
 | ---| ---| ---|
 | 3 | 3 | 0 |
 | -4 | -1 | -1 |
 | 2 | 1 | -1 |
 | -3 | -2 | -2 |
 | -2 | -4 | -4 |
 | 7 | 3 | -4 |

 最低余额为-4，因此法师需要4点起始法力。 为旅程的每个点添加 4 可防止余额变为负数。 

第二个例子：```
5
5 -2 -8 4 10
```| 来源价值| 当前余额| 最低余额 |
 | ---| ---| ---|
 | 5 | 5 | 0 |
 | -2 | 3 | 0 |
 | -8 | -5 | -5 |
 | 4 | -1 | -5 |
 | 10 | 10 9 | -5 |

 最低的模拟平衡为-5，因此所需的初始法力值为5。这个例子表明，最后的大量恢复并不能帮助解决早期的危险点。 

# 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个源都被处理一次。 |
 | 空间| O(1) | O(1) | 仅存储当前总和和最小前缀值。 |

 该解决方案很容易满足约束条件，因为它对最多 500000 个值执行单次线性扫描，并且不会分配与输入大小成比例的内存。 

# 测试用例```python
import sys
import io

def solve_io(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    import builtins

    a = list(map(int, input().split()))

    minimum = 0

    for x in a:

 # 边缘情况

 对于全阳性的情况：```
3
5 2 8
```运行余额为 5、7 和 15。最小前缀值保持为零，因为模拟法师永远不会损失法力。 算法返回`-0`，这就是简单的`0`，正确处理不需要初始法力的事实。 

对于初始负值情况：```
3
-10 20 -5
```运行余额为 -10、10 和 5。最小前缀为 -10，因此答案变为 10。这符合要求，因为法师必须在恢复之前必须在第一个来源中生存。 

对于中间赤字情况：```
5
4 -7 1 1 10
```运行余额为 4、-3、-2、-1 和 9。最小值为 -3，因此答案为 3。该算法不依赖于最终的法力值，可以正确识别旅途中最危险的点。 

对于最大尺寸输入：```
500000
-1000000000 -1000000000 ... -1000000000
```每一步余额都会减少 10^9。 所有源之后的最小余额为 -500000000000000，因此答案为 500000000000000。实现会处理此问题，因为 Python 整数可以表示远大于 64 位限制的值。
