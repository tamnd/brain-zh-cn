 ## 解决方案
 # 问题理解

 该图描述了由双向边连接的顶点网络。 每条边上都附有一个小写字母。 沿着从顶点 1 到顶点 n 的路径移动，会根据边缘上遇到的字母创建一个字符串。 在所有边数最少的路径中，我们需要选择生成的字符串按字典顺序最小的路径，然后打印顶点和字符串。 

该图最多可包含 200,000 个顶点和 200,000 条边。 在几秒的限制下，需要一种算法来探索每个边或顶点的少量恒定工作量。 枚举路径、尝试所有选择组合或重复执行对许多候选者的搜索的方法将呈指数增长或至少超过可用时间。 O(n + m) 左右的解决方案是目标，因为它与输入大小匹配。 

困难在于最短路径条件和词典编序条件是相互作用的。 如果首字母较小的路径比最短距离长，则该路径是无用的。 具有正确长度的路径仍然可能会丢失，因为后面的字符更大。 该算法必须仅保留仍然可以成为最佳的路径。 

一个简单的错误是立即从顶点 1 中选择最小的边。 考虑：```
4 4
1 2 b
2 4 a
1 3 a
3 4 z
```最短路径的长度为 2。选择最小的第一条边给出路径 1 到 3 到 4 以及字符串`az`，这是正确的。 然而，不限于最短路径层的贪婪方法可能会在其他图中失败，因为跟随一个小字母进入死胡同或更长的路线。 

另一个常见错误是运行 BFS 并采用找到的第一条最短路径。 考虑：```
3 3
1 2 b
2 3 a
1 3 z
```最短路径的长度为 1，所以答案是：```
1
1 3
z
```在检查距离之前更喜欢小写字母的搜索可能会选择路径`ba`，但该路径根本不是最短路径。 

当多个顶点共享相同的最佳前缀时，就会出现第三个问题。 考虑：```
5 5
1 2 a
1 3 a
2 5 b
3 4 a
4 5 b
```最好的字符串是`ab`。 选择第一个字母后`a`，顶点 2 和 3 仍然是候选点。 过早丢弃顶点 3 可能会删除唯一给出最佳答案的延续。 

## 方法

 直接的暴力解决方案将生成从顶点 1 到顶点 n 的所有路径，仅保留那些长度最小的路径，并比较它们的字符串。 这是正确的，因为它准确地检查了所需的候选人集。 问题在于图中的路径数量可能非常巨大。 具有许多分支边的图可以具有指数级的许多不同路径，因此这种方法甚至无法在中等输入上完成。 

更好的尝试是从顶点 1 运行 BFS，因为 BFS 给出未加权图中的最短距离。 之后，我们可以在浏览图表时尝试选择最小的字母。 缺少的部分是知道哪些顶点仍然可以参与最短路径。 如果没有这些信息，一个小字母可能会偏离目标。 

关键的观察结果是距离将所有有效的最短路径划分为多个层。 设顶点1到顶点n的最短距离为L。只有当顶点到顶点1的距离为i且到顶点n的距离为L - i时，顶点才能出现在最短路径的位置i。 一旦知道了这些有效层，每个有效的移动总是从第 i 层到第 i + 1 层。 

现在，词典编纂的选择变得本地化了。 在每一层，我们都有一组共享迄今为止找到的最佳前缀的顶点。 我们检查所有继续到下一个有效层的传出边缘，选择其中最小的字母，并使用该字母保持每个目的地均可到达。 保留所有这样的顶点是必要的，因为几个前缀可以保持联系，直到后面的字符将它们分开。 

两次 BFS 运行找到最短路径结构。 然后，贪婪层处理在该结构内构造最小的字符串。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(路径数) | O(n) | 太慢了|
 | 具有贪婪重建的 BFS 层 | O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 从顶点1运行BFS并存储`dist_start`，从源到每个顶点的最短距离。 从顶点 n 运行另一个 BFS 并存储`dist_end`，从每个顶点到目的地的最短距离。 
2.让`length = dist_start[n]`。 仅当一个顶点属于最短路径时`dist_start[v] + dist_end[v] == length`。 这会删除所有不能成为最佳路线一部分的顶点。 
3. 从仅包含顶点 1 的当前集合开始。对于从 0 到`length - 1`，检查离开当前集的所有边。 只考虑边缘`(u, v)`什么时候`v`位于下一个最短路径层。 
4. 找到所有考虑的边中最小的字符。 该字符必须是答案的下一个字符，因为每个其他候选字符都会在它们不同的第一个位置使字符串变大。 
5. 通过采用具有最小字符的边缘可到达的每个目的地来构建下一组。 为每个新添加的顶点存储一个父顶点，以便稍后可以重建有效路径。 
6. 处理完所有层后，选择最终集合中的任意顶点并向后跟踪存储的父顶点，直到到达顶点 1。反转此顺序以获得路径。 

为什么它起作用：在每一层，当前集合恰好包含可以出现在迄今为止构造的最小前缀之后的顶点。 当我们选择尽可能小的下一个字符时，使用较大字符的每条路径在字典顺序上都会立即变得更糟。 将每个目标保留为该字符可以保留仍然共享最佳前缀的所有可能的延续。 由于每个转换都位于最短路径层内，因此最终路径具有最小长度。 不变量在每一层之后都保持不变，因此完整的字符串是所有最短路径中最小的。 

## Python 解决方案```python
import sys
from collections import deque

input = sys.stdin.readline

def bfs(start, graph):
    n = len(graph) - 1
    dist = [-1] * (n + 1)
    dist[start] = 0
    q = deque([start])

    while q:
        u = q.popleft()
        for v, _ in graph[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)

    return dist

def solve():
    n, m = map(int, input().split())
    graph = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v, c = input().split()
        u = int(u)
        v = int(v)
        graph[u].append((v, c))
        graph[v].append((u, c))

    dist_start = bfs(1, graph)
    dist_end = bfs(n, graph)

    length = dist_start[n]

    parent = [0] * (n + 1)
    current = {1}
    answer_chars = []

    for layer in range(length):
        best = '{'
        for u in current:
            for v, c in graph[u]:
                if dist_start[v] == layer + 1 and dist_start[v] + dist_end[v] == length:
                    if c < best:
                        best = c

        answer_chars.append(best)

        nxt = set()
        for u in current:
            for v, c in graph[u]:
                if c == best and dist_start[v] == layer + 1 and dist_start[v] + dist_end[v] == length:
                    if v not in nxt:
                        parent[v] = u
                        nxt.add(v)

        current = nxt

    end = next(iter(current))
    path = []

    while end != 0:
        path.append(end)
        end = parent[end]

    path.reverse()

    out = []
    out.append(str(length))
    out.append(" ".join(map(str, path)))
    out.append("".join(answer_chars))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```两个 BFS 调用是独立的最短距离计算。 由于图是未加权的，因此队列就足够了，并且每条边仅检查恒定次数。 

主循环代表贪婪构造。 变量`current`是共享已选择的最佳前缀的顶点集。 条件`dist_start[v] + dist_end[v] == length`过滤掉不能属于任何最短路径的边。 

父数组存储顶点首次进入下一层时选择的前趋。 顶点仅出现在一个距离层中，因此这个单个父值足以用于重建。 最终的向后遍历会产生最佳路径之一，即使多条路径具有相同的最小字符串。 

人物`'{`用作初始值，因为按字典顺序它比每个小写英文字母都大。 Python 字符串通过 ASCII 值比较字符，因此这对于输入字母表来说是安全的。 

## 工作示例

 对于第一个样本：```
3 2
1 2 a
2 3 b
```最短距离为 2。有效的最短路径层为 1、2、3。 

| 层 | 当前顶点 | 选择的角色 | 下一个顶点 |
 | ---| ---| ---| ---|
 | 0 | {1} | 一个 | {2} |
 | 1 | {2} | 乙| {3} |

 遵循唯一可能的路线。 该不变量成立，因为在每一步之后，集合包含可以产生最佳前缀的所有顶点。 

对于第二个样本：```
3 3
1 3 z
1 2 a
2 3 b
```直接边比通过顶点 2 的路线短。 

| 层 | 当前顶点 | 选择的角色 | 下一个顶点 |
 | ---| ---| ---| ---|
 | 0 | {1} | z | {3} |

 图层限制删除了路径`1 -> 2 -> 3`因为它的长度是2，而最短距离是1。这说明了为什么距离信息必须与字典选择结合起来。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + m) | BFS 遍历和贪婪层处理都线性地检查图。 |
 | 空间| O(n + m) | 邻接列表存储所有边，数组存储距离、父项和临时集。 |

 输入限制需要线性解。 对于 200,000 个顶点和边，O(n + m) 可以保持在时间限制内，而任何依赖于枚举路径或重复搜索许多候选路径的方法都不会。

 ## 边缘情况

 第一种边缘情况是直接边缘击败字典顺序较小的较长路径的情况。 

输入：```
3 3
1 3 z
1 2 a
2 3 b
```1到3的BFS距离为1。贪婪构造时，只有距离为1的顶点才被视为下一层。 顶点 2 被排除，因为到达它需要另一条边。 该算法输出唯一的最短路径：```
1
1 3
z
```第二种边缘情况是多个顶点共享相同的前缀。 

输入：```
5 5
1 2 a
1 3 a
2 5 b
3 4 a
4 5 b
```最短长度为2。选择后`a`，当前集合变为`{2, 3}`。 下一层包含边缘`2 -> 5`和`4 -> 5`，但仅`2 -> 5`来自当前集合，所以最终的字符串是`ab`。 该算法不会过早地提交到一个顶点。 

第三种边缘情况是当图形包含许多相同的字母时。 

输入：```
6 6
1 2 a
2 6 a
1 3 a
3 4 a
4 6 a
1 5 b
```最短距离为 2。两者`1 -> 2 -> 6`和`1 -> 3 -> 4 -> 6`开始于`a`，但第二条路线较长，并被图层条件删除。 该算法仅考虑向前移动一个最短路径层的边，因此它输出：```
2
1 2 6
aa
```
