 ## 解决方案
 ## 问题理解

 该树表示连接顶点的网络。 操作选择两个顶点并为它们之间的唯一路径上的每个顶点和边着色。 目标是找到一起覆盖树的每个部分的最小数量的所选路线。 

输入描述了树的连接。 由于一棵树与`n`顶点总是有`n - 1`边缘，整个结构由这些连接定义。 输出是绘制整棵树所需的最少路径选择数。 

约束条件`n <= 200000`改变我们处理问题的方式。 探索许多可能路径或针对每个选择重复执行树遍历的解决方案将不符合 2 秒的限制。 我们需要一种接近线性时间的算法，因为输入本身包含多达大约二十万条边。 周围的一切`O(n^2)`或者更糟糕的是太慢了。 

一个常见的错误是只关注叶子。 叶子确实很重要，因为它们是绘画路径的自然端点，但具有奇数度数的内部顶点也会影响答案。 例如，在一棵中心有三个分支的树中，仅计算叶子会给出错误的直觉，因为中心本身必须充当某些路径排列中的端点。 

考虑这棵树：```
4
1 2
3 2
4 2
```正确答案是`2`。 一种粗心的只计算三个叶子的方法可能会认为一条路径就足够了，因为一条路径可以连接两个叶子并穿过中心，但一次操作无法覆盖所有三个分支。 中心有学位`3`，因此也在那里创建了必要的端点之一。 

另一个边界情况是一个简单的链：```
5
1 2
2 3
3 4
4 5
```答案是`1`。 始终返回叶数除以二的解决方案在这里是可行的，但假设每个分支点都需要单独的操作的解决方案可能会错误地返回更大的值。 链的两个端点是唯一的奇数度顶点。 

## 方法

 直接的方法是生成树中的每个可能的路径，然后搜索这些路径的并集包含每个边的最小集合。 有`O(n^2)`可能的端点对，并且检查它们的每个子集是指数级的。 即使进行了优化，这很快就变得不可能了`n = 200000`。 

暴力破解之所以有效，是因为每个有效答案确实都是路径的集合，但它会失败，因为可能的集合数量远远大于输入大小。 

关键的观察来自于查看顶点度数。 每次我们使用路径操作时，该路径的两个端点是所使用的路径贡献奇数个入射路径边的唯一位置。 路径的所有内部顶点都接收两条路径边，因此它们不会影响奇偶校验。 

如果我们选择覆盖整棵树的多条路径，则需要作为这些路径端点的顶点正是度数为奇数的顶点。 一条路径可以固定两个奇数度的顶点，因为它有两个端点。 这给出了一个下界：如果树有`x`至少奇数度顶点`x / 2`需要路径。 

这个下限也是可以实现的。 我们可以将奇数度顶点配对，并使每一对成为一条路径的端点。 路径可能在顶点重叠，这是允许的，因为多次绘制某物不会产生负面影响。 树的每个边都可以包含在这个配对过程中，因此不需要额外的路径。 

答案很简单，就是度数为奇数的顶点数量的一半。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 可能的路径数量呈指数增长 | O(n) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取树的边并存储每个顶点的度数。 每条边都会增加其两个端点的度数，因为度数告诉我们有多少分支离开一个顶点。 
2. 计算有多少个顶点的度数为奇数。 这些顶点不能完全通过路径的内部点来处理，因此它们必须显示为端点。 
3. 将此计数除以二并输出结果。 每个操作恰好贡献两个端点，并且配对参数表明这个操作数量总是足够的。 

为什么它有效：

 重要的不变量是顶点度数的奇偶性。 路径操作将树的视角更改为已使用路径边的集合。 在绘制的路径内，每个非端点顶点都会收到两条已使用的边，以保持其奇偶性均匀。 只有路径端点才提供奇奇偶校验。 由于原始树恰好具有需要表示为端点的奇数度顶点，因此任何解决方案至少需要奇数顶点一半的路径。 将这些奇数顶点配对成路径就达到了该界限，因此最小值恰好是奇数度顶点的数量除以二。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    degree = [0] * (n + 1)

    for _ in range(n - 1):
        u, v = map(int, input().split())
        degree[u] += 1
        degree[v] += 1

    odd = 0
    for i in range(1, n + 1):
        if degree[i] % 2 == 1:
            odd += 1

    print(odd // 2)

if __name__ == "__main__":
    solve()
```数组`degree`仅存储树所需的信息。 我们不需要邻接表，因为最终答案仅取决于每个顶点的度奇偶性。 

读取每个边缘时，两个端点都会获得一个入射边缘，因此两个度数都会递增。 处理完所有边后，循环对度数为奇数的顶点进行计数。 

一棵树总是有偶数个奇数度顶点，因此整数除以二给出了所需操作的确切数量。 Python 整数处理最大度值而不会出现任何溢出问题。 

## 工作示例

 ### 示例 1

 输入：```
5
1 2
1 3
1 4
1 5
```这棵树是一颗星星。 中心有学位`4`，所有四片叶子都有度数`1`。 

| 步骤| 考虑的学位| 奇数计数 | 回答 |
 | ---| ---| ---| ---|
 | 读完边缘| 1:4、2:1、3:1、4:1、5:1 | 4 | 2 |
 | 最终计算| 四个奇数顶点需要配对 | 4 | 4 / 2 = 2 | 4 / 2 = 2

 这四个叶子是唯一的奇数度顶点。 两条路径可以将它们配对：一条路径覆盖穿过中心的两片叶子，另一条路径覆盖剩余的两片叶子。 

### 示例 2

 输入：```
5
1 2
2 3
3 4
4 5
```这是一条直链。 

| 步骤| 考虑的学位| 奇数计数 | 回答 |
 | ---| ---| ---| ---|
 | 读完边缘| 1:1、2:2、3:2、4:2、5:1 | 2 | 1 |
 | 最终计算| 只有两端是奇数| 2 | 2 / 2 = 1 | 2 / 2 = 1

 整个链条已经是一条路径，所以一次操作就足够了。

 ## 边缘情况

 对于三节点星：```
3
1 2
1 3
```度数是`1, 2, 1`。 有两个奇数度顶点，因此算法输出`1`。 从顶点出发的一条路径`2`到顶点`3`绘制整棵树。 

对于四节点星形：```
4
1 2
1 3
1 4
```度数是`3, 1, 1, 1`。 所有四个顶点都是奇数。 该算法计算四个奇数顶点并返回`2`。 一次操作可以通过中心连接两个叶子，但剩余的分支需要第二次操作。 

对于五节点链：```
5
1 2
2 3
3 4
4 5
```只有顶点`1`和`5`有奇数学位。 算法返回`1`，因为选择这两个端点会绘制整个链。 这证实了长路径不需要分成更小的操作。 

对于分支顶点为奇数的树：```
4
1 2
3 2
4 2
```顶点`2`有学位`3`，叶子也有度数`1`。 奇数个数是`4`，所以答案是`2`。 该算法将中心纳入奇偶校验计算中，避免了只计算叶子的错误。
