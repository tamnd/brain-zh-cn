 ## 解决方案
 ## 问题理解

 数组哈希过程重复删除前两个值并用它们的差值替换它们。 我们需要了解在所有操作之后哪些值仍然存在，而不是模拟这些删除。 输入给出一个初始数组和一系列范围添加。 每次更新都会将选定间隔中的每个元素增加相同的数量，并且每次更新后我们必须打印整个数组的当前哈希值。 

问题的关键是找到哈希的形式。 对于数组`[a1, a2, a3, a4]`，过程变为`[a2-a1, a3, a4]`， 然后`[a3-(a2-a1), a4]`，最后`a4-(a3-a2+a1)`。 简化给出`a4-a3-a2-a1`。 对于较大的数组，同样的模式仍然存在：最终的哈希值始终是最后一个元素减去所有先前元素的总和。 

这些约束迫使我们避免在每次查询后模拟哈希。 该数组最多可以包含 500,000 个元素，并且可以有 200,000 个更新。 对于每个查询都扫描数组的解决方案在最坏的情况下将执行大约 1000 亿次操作，这无法满足 2 秒的限制。 我们需要一个每次更新都需要恒定时间的解决方案。 

一些边界情况可能会破坏粗心的实现。 当数组只有一个元素时，散列就是该元素本身。 例如：```
Input:
1
5
1
1 1 3

Output:
8
```假设总是有一个单独的最后一个元素和一个前缀的解决方案在这里会失败。 

另一个棘手的情况是到达最后位置的更新。 例如：```
Input:
3
1 2 3
1
2 3 5

Output:
1
```数组变成`[1,7,8]`。 哈希值是`8-1-7=0`等等，这个例子说明了为什么必须小心应用公式。 正确的哈希是`a3-a1-a2 = 8-1-7 = 0`。 

一个常见的错误是只更新第一个的存储总和`n-1`元素并忘记最后一个元素有不同的符号。 在这种情况下，最后一个位置接收更新并且必须单独跟踪。 

范围更新还可以部分重叠前缀和最终元素。 例如：```
Input:
4
1 2 3 4
1
3 4 10

Output:
0
```新的数组是`[1,2,13,14]`，所以哈希是`14-1-2-13=-2`。 更新同时影响负号元素和正号元素，因此统一处理整个范围会给出错误的结果。 

## 方法

 直接的方法是存储数组，通过访问每个受影响的位置来应用每个范围加法，然后模拟哈希操作或重新计算公式。 这是正确的，因为它完全遵循定义。 但是，一个查询可以触及每个元素，并且可以有 200,000 个查询。 在最坏的情况下，这大约会产生`200000 * 500000 = 100000000000`元素修改，这远远超出了可能的范围。 

重要的观察是，看起来复杂的哈希运算实际上是一个固定的线性表达式。 除最后一个元素外，每个元素都有系数`-1`，最后一个元素贡献系数`+1`。 范围更新将相同的值添加到一组仓位中，因此我们只需要知道有多少个更新仓位属于负组以及是否包含正仓位。 

蛮力方法之所以有效，是因为它保留了每个个体的值，但它却失败了，因为它重复了不必要的工作。 对哈希公式的观察将整个问题简化为维护两个数字：第一个数字的和`n-1`元素和最后一个元素的值。 每个查询仅更改这两个值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(nq) | O(n) | 太慢了|
 | 最佳| O(q) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 计算除最后一个元素之外的所有元素的总和，并单独存储最后一个元素。 任何时刻的答案都是`last - prefix_sum`，所以这两个值完整地描述了哈希值。 
2. 每次更新`[l, r]`有价值`v`，找出该区间中有多少个位置在第一个区间内`n-1`元素。 如果`l <= n-1`，这个计数是`min(r, n-1) - l + 1`。 添加`count * v`到存储的前缀和，因为所有这些位置都有系数`-1`在哈希中。 
3. 检查区间是否包含位置`n`。 如果`r == n`， 添加`v`到存储的最后一个元素，因为最终位置有系数`+1`。 
4. 打印`last - prefix_sum`应用更新后。 存储的值已经代表了所有先前操作的整体效果，因此不需要重建数组。 

工作原理：哈希函数是数组值的线性组合。 范围添加只会改变受影响位置的总贡献。 该算法分别保留了负系数位置和正系数位置的准确贡献。 由于每次更新都会通过添加到其位置的精确量来修改这些贡献，因此存储的表达式始终等于真实的哈希值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    if n == 1:
        prefix_sum = 0
        last = a[0]
    else:
        prefix_sum = sum(a[:-1])
        last = a[-1]

    q = int(input())
    ans = []

    for _ in range(q):
        l, r, v = map(int, input().split())

        if n > 1 and l <= n - 1:
            right = min(r, n - 1)
            prefix_sum += (right - l + 1) * v

        if r == n:
            last += v

        ans.append(str(last - prefix_sum))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```代码存储`prefix_sum`作为持仓总数`1`通过`n-1`，因为所有这些位置在最终哈希中都有负号。 变量`last`存储唯一带有正号的位置。 

对于每个查询，与前缀的交集计算如下`min(r, n-1)`。 这可以避免意外触及最后一个元素。 条件`l <= n - 1`处理在前缀之后开始的更新。 

仅当以下情况时才更新最后一个元素`r == n`，因为区间恰好在其右端点为时到达最终位置`n`。 所有值都可以变大，但Python整数自动支持所需的范围，因此不需要溢出处理。

 ## 边缘情况

 对于单元素数组，哈希就是该元素，因为不存在负系数位置。 输入：```
1
5
1
1 1 3
```以哈希开头`5`。 更新将唯一的元素更改为`8`，算法更新`last`因为区间包含最终位置。 存储的前缀和保持为零，给出`8 - 0 = 8`。 

对于包含最终位置的更新，最后一个元素不能混合到前缀和中。 考虑：```
3
1 2 3
1
2 3 5
```更新后的数组是`[1,7,8]`。 前缀和从`3`到`8`因为位置2增加了，最后的值从`3`到`8`。 哈希值变为`8 - 8 = 0`。 对每个更新位置应用相同符号的方法在这里会失败。 

对于部分重叠两组的更新，请考虑：```
4
1 2 3 4
1
3 4 10
```只有位置 3 对前缀和有贡献，位置 4 对最后一个值有贡献。 该算法添加`10`到前缀和和`10`到最后一个值，除了现有的符号外，保持差值不变。 最终的哈希值是`14 - (1 + 2 + 13) = -2`，匹配维护的表达式。
