 ## 解决方案
 ## 问题理解

 每个通知都会在特定时刻到达，并包含给定持续时间的视频。 Vasya 总是按照通知到达的顺序观看视频。 如果他在出现通知时处于空闲状态，他会立即开始观看该视频。 如果他已经在观看某些内容，则新视频会在队列中等待，直到观看完之前所有未完成的视频。 

输入已经按照到达时间的非递减顺序给出通知，因此我们永远不需要重新排序它们。 任务只是在处理每个通知后确定最终视频的完成时间。 

通知数量达到200000条，而到达时间和持续时间都可以高达（10^9）。 任何重复模拟时间或扫描先前处理的通知以查找每个新通知的算法都会执行太多操作。 线性解决方案很容易足够快，而二次方法则被排除在外。 由于完成时间可能超过 (2 × 10^9)，因此该算法还必须避免假设值适合 32 位整数，尽管 Python 整数自然可以处理此问题。 

一个容易犯的错误是忘记 Vasya 可以在下一个通知到达之前变得空闲。 

例子：```
2
1 2
10 3
```正确答案是`13`。 Vasya及时完成了第一个视频`3`，等到时间`10`，然后观看第二个视频，直到`13`。 简单地将持续时间添加到先前的完成时间会错误地产生`6`。 

当多个通知同时到达时，会发生另一种微妙的情况。```
3
5 2
5 4
5 1
```正确答案是`12`。 第一个视频立即开始`5`，另外两个按到达顺序附加在其后面。 将具有相同时间戳的通知视为同时发生的独立事件会丢失该顺序。 

第三种情况是通知恰好在上一个视频结束时到达。```
2
1 4
5 3
```正确答案是`8`。 时`5`Vasya 不再忙，所以第二个视频立即开始。 使用严格的比较，例如`finish > arrival`而不是`finish >= arrival`可能会错误地改变时间表。 

## 方法

 简单的模拟将每个等待的视频保留在队列中。 每当通知到达时，模拟都会提前时间，删除每个已完成的视频，然后立即启动到达的视频或将其附加到队列中。 这忠实地模拟了规则，但在最坏的情况下，每个到达可能会再次处理许多排队的视频。 对于 (n) 个通知，这可能需要 (O(n^2)) 工作，当 (n = 200000) 时大约需要 (4 \times 10^{10}) 次操作。 

队列本身实际上是不必要的。 在任何时刻，影响未来通知的唯一信息是 Vasya 恢复自由的时间。 假设在处理完一些通知后，他保证会保持忙碌直到时间`finish`。 当新通知到达时`t`，只有两种情况可能。 

如果`finish <= t`，出现通知时 Vasya 处于空闲状态。 新视频开始于`t`并结束于`t + d`。 

如果`finish > t`，瓦夏依然忙碌。 新视频正好开始于`finish`并结束于`finish + d`。 

这两种情况都可以用一个公式来表达：```
finish = max(finish, t) + d
```这个单个变量完全捕获整个监视队列的状态，允许每个通知被处理一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 初始化`finish = 0`。 在任何通知到达之前，Vasya 都处于闲置状态。 
2. 按照给定的顺序一一阅读通知。 输入已按到达时间排序，因此无需进行预处理。 
3. 对于每个通知以及到达时间`t`和持续时间`d`, 计算`start = max(finish, t)`。 如果 Vasya 仍然很忙，则视频会等到`finish`。 否则它立即开始于`t`。 
4. 更新`finish = start + d`。 这成为每个处理的通知都被完全观看的最早时刻。 
5.所有通知处理完毕后，输出`finish`。 

### 为什么它有效

 关键的不变量是在处理第一个之后`i`通知，`finish`等于观看所有这些视频的确切时间。 当下一个通知到达时，较早的视频不能晚于`finish`，因为之前的每个通知都已经安排好了。 如果 Vasya 空闲，新视频会立即开始。 如果他很忙，则每个较早的视频都必须在新视频开始之前完成，因此最早的开始时间恰好是`finish`。 更新中`finish`和`max(finish, t) + d`保留不变量，在最后一次通知之后，它表示最终视频的完成时间。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    finish = 0

    for _ in range(n):
        t, d = map(int, input().split())
        finish = max(finish, t) + d

    print(finish)

if __name__ == "__main__":
    solve()
```该解决方案仅保留一个变量，`finish`，表示当前计划的结束。 每个通知都会使用算法中导出的公式更新此值。 

表达式`max(finish, t)`处理两种可能的状态而不分支。 如果 Vasya 已经很忙，则当前的日程安排将继续不间断。 如果他已经完成了所有事情，则时间表将从通知到达时间重新开始。 

比较使用`max`而不是严格的不平等，它可以正确处理在上一个视频结束时准确到达的通知。 Python 整数会根据需要自动增长，因此即使非常长的完成时间也是安全的。

import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())
    finish = 0
    for _ in range(n):

        finish = max(finish, t) + d

def run(inp: str) -> str:

    backup_stdout = sys.stdout

    out = io.StringIO()
    sys.stdout = out
    solve()
    sys.stdin = backup_stdin
    sys.stdout = backup_stdout
    return out.getvalue().strip()

 ## 边缘情况

 考虑空闲间隙：```
2
1 2
10 3
```该算法开始于`finish = 0`。 第一次通知后，`finish = max(0, 1) + 2 = 3`。 对于第二次通知，`finish = max(3, 10) + 3 = 13`。 时间表正确地在时间重新启动`10`而不是从时间上继续`3`。 

现在考虑具有相同时间戳的多个通知。```
3
5 2
5 4
5 1
```更新内容是`7`， 然后`11`， 然后`12`。 每个通知都按输入顺序进行处理，因为每个新的开始时间都取决于较早通知生成的完成时间。 

最后，考虑在上一个视频结束时恰好收到通知。```
2
1 4
5 3
```第一次通知后，`finish = 5`。 第二次更新变成`max(5, 5) + 3 = 8`。 自从`finish`和到达时间相等，新视频立即开始，没有任何不必要的等待，符合所需的行为。
