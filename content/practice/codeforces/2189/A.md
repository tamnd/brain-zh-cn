 ## 解决方案
 ## 问题理解

 我们有一个数字数组。 我们可以从中选择任意偶数个元素并将它们划分为有序对。 

一对`(x, y)`贡献`1`仅当行`x`和列`y`存在。 由于表中有`h`行和`l`列，这意味着我们需要`1 ≤ x ≤ h`和`1 ≤ y ≤ l`。 

接收增量的实际单元格对于最终答案并不重要。 该问题要求表中所有值的总和。 每个有效对恰好增加一个单元格`1`，因此最大化表总和相当于最大化我们可以形成的有效对的数量。 

数组长度最多为`100`，很小。 即使效率相当低的解决方案也能轻松适应。 挑战不在于性能，而在于识别正确的贪婪观察。 

一个数字最多只能使用一次，因为我们从数组中选择元素并将它们配对。 如果同一值在数组中出现多次，则可能会出现多次。 

主要的微妙之处在于一对中的两个位置具有不同的作用。 用作第一个元素的数字最多只能是`h`，而用作第二个元素的数字最多只能是`l`。 满足这两个条件的值可以充当任一角色。 

考虑`h = 2`,`l = 5`，和数组`[1, 1, 1]`。 所有三个数字都是有效的行和列。 粗心的解决方案可能会计算出三个可用的数字并给出答案`3`，但一对消耗两个数字，因此只能形成一对有效的对。 正确答案是`1`。 

另一个棘手的情况是数字仅在一个角色中有效。 认为`h = 1`,`l = 100`，和数组`[1, 50]`。 价值`1`可以是一行和一列，而`50`只能是一列。 我们可以形成`(1, 50)`，给出答案`1`。 单独计算行数和列数而不跟踪重用的解决方案可能会错误地认为可以进行更多配对。 

当没有数字可以用作行时，就会出现最后的边缘情况。 例如：```
n = 2, h = 1, l = 1
a = [5, 5]
```不存在有效的对，所以答案是`0`。 

## 方法

 蛮力思维首先会问可以组成哪些对。 每个元素都可以不使用、成为一对的第一个成员或成为一对的第二个成员。 探索所有可能的配对很快就变成了组合。 即使是为了`n = 100`，可能的匹配数量是天文数字。 

关键的观察是我们不关心哪个有效单元接收增量。 每对成功的搭档都做出了准确的贡献`1`到答案。 

让我们根据每个数组元素可以扮演的角色对其进行分类。 

如果一个值`x`满足`x ≤ h`，它可以作为行索引。 

如果一个值`x`满足`x ≤ l`，它可以作为列索引。 

为了使一对有效，必须为一个选定元素分配行角色，并且必须为另一个选定元素分配列角色。 

假设我们一次处理一个数组元素。 每个有效对都需要一个支持行的元素和一个支持列的元素。 满足这两个条件的元素是灵活的，可以填补当前需要的任何角色。 

这就变成了行槽和列槽之间的匹配问题。 由于每对恰好消耗两个元素，因此有效对的最大数量等于可以创建的行列匹配的最大数量。 

一个非常简单的贪心工程。 

维护我们看到了多少不匹配的行元素和我们看到了多少不匹配的列元素。 

处理新号码时：

 如果它可以作为行，我们希望立即将其与先前不匹配的列元素（如果存在这样的元素）配对。 

类似地，如果它可以用作列，我们希望将其与先前不匹配的行元素（如果存在这样的元素）配对。 

更清晰的视图是将元素分为三类。 

价值观与`x ≤ min(h,l)`可以扮演任何一个角色。 

价值观与`min(h,l) < x ≤ h`只能是行。 

价值观与`min(h,l) < x ≤ l`只能是列。 

让`R =`可行元素的计数（`x ≤ h`）`C =`可列元素的计数（`x ≤ l`）

 每个有效对都需要一个行角色和一个列角色。 如果我们创建`k`对，我们消费`k`行分配和`k`列分配。 由于每个数组元素只能使用一次，因此消耗的元素总数为`2k`，不得超过`n`。 

灵活的元素自动解决角色分配冲突。 最大可能的对数很简单：`min(R, C, n // 2)`要了解原因，我们需要`k ≤ R`因为每一对都需要一个行元素，`k ≤ C`因为每一对都需要一个列元素，并且`k ≤ n/2`因为每一对消耗两个元素。 

这些边界也是可以实现的，因为可以将灵活的元素分配给缺少的一侧。

 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 统计有多少个数组元素满足`a[i] ≤ h`。 调用这个值`R`。 
2. 统计有多少个数组元素满足`a[i] ≤ l`。 调用这个值`C`。 
3. 每个有效对都需要一个能够行的元素和一个能够列的元素，因此对的数量不能超过其中之一`R`或者`C`。 
4. 每对也消耗两个数组元素，因此对的数量不能超过`n // 2`。 
5、答案是：```
min(R, C, n // 2)
```6. 输出测试用例的答案。 

### 为什么它有效

 有效对只不过是一个分配给行位置的元素和另一个分配给列位置的元素。 

如果我们想创建`k`有效对，我们至少需要`k`能够行的元素并且至少`k`可列的元素，给出边界`k ≤ R`和`k ≤ C`。 由于每一对使用两个不同的数组元素，我们还需要`2k ≤ n`，这给出了`k ≤ n // 2`。 

这是唯一的限制。 满足这两个条件的任何元素都可以分配给所需的角色。 因此，每当`k`满足所有三个不等式，则构造存在。 最大可行值恰好是`min(R, C, n // 2)`。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n, h, l = map(int, input().split())
        a = list(map(int, input().split()))
        
        rows = sum(x <= h for x in a)
        cols = sum(x <= l for x in a)
        
        print(min(rows, cols, n // 2))

solve()
```实现直接遵循数学特征。 

变量`rows`计算有多少个元素有资格用作一对的第一个成员。 变量`cols`计算有多少元素有资格用作第二个成员。 

最终答案受到所有三个必要限制的限制。 取最小值给出可实现的最大有效对数。 

不存在溢出问题，因为所有值都很小。 唯一值得检查的细节是每个测试用例都准确包含`n`数字和那个`n // 2`使用整数除法，因为小数对是不可能的。

 ## 边缘情况

 ### 所有数字都太大

 输入：```
1
2 1 1
5 5
```我们数一下：```
rows = 0
cols = 0
n // 2 = 1
```该算法返回：```
min(0, 0, 1) = 0
```没有元素可以充当行索引或列索引，因此不存在有效的对。 

### 许多可用的数字，但没有足够的元素来容纳更多对

 输入：```
1
3 10 10
1 2 3
```我们得到：```
rows = 3
cols = 3
n // 2 = 1
```答案变成：```
min(3, 3, 1) = 1
```虽然每个元素在两种角色中都有效，但只存在三个元素，因此最多可以形成一对。 

### 行候选和列候选之间的严重不平衡

 输入：```
1
6 5 2
1 2 3 4 5 5
```计数：```
rows = 6
cols = 2
n // 2 = 3
```该算法返回：```
min(6, 2, 3) = 2
```只有两个元素可以充当列，因此无论有多少可用的行元素，都无法创建第三个有效对。 

### 值在两个角色中都有效

 输入：```
1
4 1 1
1 1 1 1
```计数：```
rows = 4
cols = 4
n // 2 = 2
```回答：```
min(4, 4, 2) = 2
```每个元素都很灵活，可以分配任一角色。 该算法正确地识别出可以形成两对。
