 ## 解决方案
 ## 问题理解

 我们有一棵树。 顶点`i`最初包含`a_i`坚果。 

电费有两种。 

第一个成本来自特殊的重新分配操作。 我们选择一个顶点`v`。 然后每隔一个顶点从较大距离到较小距离进行处理`v`。 如果已处理的顶点当前包含至少一个螺母，则恰好将一个螺母移动到更靠近的一条边`v`。 

第二个成本是在所有重新分配操作完成之后产生的。 Zhora 从每个非空顶点吃坚果，支付`q`对于仍包含至少一个螺母的每个顶点。 

我们的目标是决定执行多少次重新分配操作，以及围绕哪些顶点，以便最小化移动成本和进食成本的总和。 

首先要了解重新分配操作的真正作用。 

固定中心顶点`v`。 Consider one operation around`v`。 每个顶点除了`v`最多可能会丢失一颗坚果。 该螺母将一侧边缘移向`v`。 由于顶点是从较大距离到较小距离进行处理的，因此来自子节点的坚果可以立即进一步转发到`v`如果中间顶点原本有坚果要发送。 这种排序是问题的关键结构属性。 

制约因素很大。 全部的总和`n`测试用例最多是`10^5`，所以我们需要一些东西`O(n log n)`或者`O(n)`每个测试用例。 任何尝试所有中心并显式模拟操作的解决方案都会立即变得太慢。 甚至`O(n^2)`是不可能的，当`n = 10^5`。 

当顶点包含许多坚果时，会出现微妙的边缘情况。 

例子：```
1 - 2
a = [100, 0]
```以顶点为中心的一项操作`2`仅从顶点移动一个螺母`1`到顶点`2`，不是全部 100 个坚果。 对操作的粗心解释通常会假设所有螺母同时移动。 这是不正确的。 

另一个棘手的情况是路径。```
1 - 2 - 3 - 4 - 5
a = [1,1,1,1,1]
```以顶点为中心的两个操作`3`将所有坚果收集到顶点`3`。 答案不是由树木直径或独立移动每个螺母决定的。 该操作同时作用于所有顶点，这使得重复应用变得非常强大。 

第三个陷阱是`q = 0`。 

例子：```
1 - 2
a = [5,7]
p = 100
q = 0
```答案是`0`。 我们可以简单地从每个非空顶点免费吃东西。 任何自动尝试合并顶点的算法都会付出过高的代价。 

## 方法

 暴力方法将尝试每个可能的中心顶点，模拟重新分配操作，并跟踪非空顶点集如何演变。 

假设我们固定一个中心`v`。 让`x_u`是最初位于顶点的螺母数量`u`。 直接模拟一个操作需要遍历整棵树。 由于我们可能执行许多操作，可能达到最大距离`v`，复杂度至少变为二次。 对所有可能的中心重复此操作是完全不可行的。 

关键的观察来自于理解围绕固定中心的重复操作实际上会做什么。 

考虑远处的一个顶点`d`从选定的中心`v`。 

每个操作最多可以将一个螺母从该顶点移近一步`v`。 后`k`操作最多`k`坚果可以离开该顶点。 因此顶点保持非空当且仅当```
a_u > k
```因为每次操作只能卸下一个螺母。 

这立即揭示了更强大的东西。 表演后`k`围绕中心开展业务`v`，每个顶点的距离`v`至多是`k`可以转发来自较深顶点的所有坚果。 整个过程的表现就好像每个顶点独立做出贡献```
max(a_u - k, 0)
```剩余的坚果。 

一个顶点恰好在什么时候变成空的`a_u ≤ k`。 

进食成本仅取决于有多少顶点保持非空状态。 如果```
cnt(k) = number of vertices with a_u > k
```然后之后`k`操作的总成本为```
k * p + cnt(k) * q
```前提是每个幸存的坚果仍然可以聚集到中心周围的单个连接区域中。 

现在树结构进入了。 

对于固定的`k`，每个顶点与`a_u > k`必须保持非空。 这些顶点最多都必须位于距离内`k`远离选定的中心，否则一些坚果会滞留在更远的地方。 

因此我们需要一个中心，其到每个顶点的距离满足`a_u > k`至多是`k`。 

同样地，如果我们定义```
S(k) = { u | a_u > k }
```那么我们需要```
radius(S(k)) ≤ k
```其中半径表示从中心到集合中所有顶点的最小可能最大距离。 

经典的树事实表明，对于任何顶点子集，其半径等于```
ceil(diameter(S)/2)
```其中直径是子集中两个顶点之间的最大距离。 

因此对于给定的可行性`k`变成```
diameter(S(k)) ≤ 2k
```这将问题转化为：

 对于每一个可能`k`，检查顶点是否`a_u > k`最多有成对直径`2k`。 如果是的话，费用是```
k*p + |S(k)|*q.
```所有可行方案中的最小值`k`就是答案。 

剩下的挑战是维持活动集的直径`S(k)`当顶点消失时`k`增加。 

| 方法| 时间复杂度| 空间复杂度| 判决 |

 |---|------|---|

 | 暴力模拟 | O(n²) 或更糟 | O(n) | 太慢了 |

 | 使用 DSU 阈值维持直径 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 ### 重新制定流程

 对于固定数量的操作`k`，当且仅当顶点保持非空`a_u > k`。 

让```
S(k) = {u : a_u > k}.
```吃饭成本变成```
|S(k)| * q.
```移动成本变为```
k * p.
```唯一剩下的问题是这些幸存的顶点是否可以由单个中心提供服务。 

### 直径条件

 中心存在当且仅当每个顶点都在`S(k)`位于距离之内`k`从那个中心。 

最大距离的最小值等于`S(k)`。 

对于树指标：```
radius = ceil(diameter / 2).
```因此可行性恰好是```
diameter(S(k)) ≤ 2k.
```### 维护活动集

 作为`k`增加，当顶点离开集合时```
k >= a_u.
```因此，顶点按照其值的降序消失。 

而不是增加`k`，从大到小处理阈值，并添加值超过当前阈值的顶点。 

活动顶点恰好是`S(k)`。 

### 活动顶点的动态直径

 对于树中的一组顶点，其直径端点完全确定所有最大距离。 

维护两个活动顶点`A`和`B`代表当前直径。 

当新的顶点`x`插入：

 1. 计算`dist(x,A)`。 
2. 计算`dist(x,B)`。 
3. 如果任一距离超过当前直径长度，则更新直径端点。 

这是标准的增量直径维护技术。 

距离的答案为`O(1)`使用 LCA 预处理。 

### 评估阈值

 只有活动集发生变化的阈值才重要。 

过程值`k`按降序排列。 

对于每个阈值：

 1. 添加所有值大于的顶点`k`。 
2. 保持活动组直径。 
3.让`D`是直径长度。 
4. 阈值可行当且仅当```
D ≤ 2k.
```5. 如果可行，更新```
answer = min(answer, k*p + active_count*q).
```案例`k`比每一个都大`a_i`不留下任何活动顶点和成本`k*p`，这比精确选择更好`k=max(a_i)`对于空集，因此检查相关阈值就足够了。 

### 为什么它有效

 之后`k`操作，每个顶点最多可以贡献`k`螺母朝中心。 一个顶点超过`k`之后坚果必须仍含有坚果。 因此幸存的顶点正是那些具有`a_u > k`。 

一个中心可以处理所有幸存的顶点，前提是每个幸存者都在距离之内`k`它的。 在树度量中，这相当于幸存者集的半径最多`k`，相当于它的直径至多`2k`。 

活动集维护始终存储当前活动顶点的真实直径。 因此，每个阈值都被正确分类为可行或不可行。 在所有可行的阈值中，算法会评估精确的成本公式，因此找到的最小值就是最佳答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

LOG = 17

def solve():
    t = int(input())

    for _ in range(t):
        n, p, q = map(int, input().split())
        a = list(map(int, input().split()))

        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)

        depth = [0] * n
        up = [[0] * n for _ in range(LOG)]

        stack = [0]
        parent = [-1] * n
        parent[0] = 0

        order = [0]
        while stack:
            v = stack.pop()
            for to in g[v]:
                if to == parent[v]:
                    continue
                parent[to] = v
                depth[to] = depth[v] + 1
                stack.append(to)
                order.append(to)

        for v in range(n):
            up[0][v] = parent[v]

        for j in range(1, LOG):
            prev = up[j - 1]
            cur = up[j]
            for v in range(n):
                cur[v] = prev[prev[v]]

        def lca(a_, b_):
            if depth[a_] < depth[b_]:
                a_, b_ = b_, a_

            diff = depth[a_] - depth[b_]
            bit = 0
            while diff:
                if diff & 1:
                    a_ = up[bit][a_]
                diff >>= 1
                bit += 1

            if a_ == b_:
                return a_

            for j in range(LOG - 1, -1, -1):
                if up[j][a_] != up[j][b_]:
                    a_ = up[j][a_]
                    b_ = up[j][b_]

            return parent[a_]

        def dist(u, v):
            w = lca(u, v)
            return depth[u] + depth[v] - 2 * depth[w]

        by_value = {}
        for i, x in enumerate(a):
            by_value.setdefault(x, []).append(i)

        values = sorted(by_value.keys(), reverse=True)

        active = 0
        diameter_len = 0
        end1 = -1
        end2 = -1

        ans = n * q

        idx = 0
        m = len(values)

        current_active = 0

        for k in range(values[0], -1, -1):
            while idx < m and values[idx] > k:
                val = values[idx]

                for v in by_value[val]:
                    current_active += 1

                    if end1 == -1:
                        end1 = end2 = v
                    else:
                        d1 = dist(v, end1)
                        d2 = dist(v, end2)

                        if d1 > diameter_len:
                            diameter_len = d1
                            end2 = v
                        elif d2 > diameter_len:
                            diameter_len = d2
                            end1 = v

                idx += 1

            if diameter_len <= 2 * k:
                ans = min(ans, k * p + current_active * q)

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案从标准 LCA 预处理开始。 在保持活动集直径的同时，需要多次确定任意顶点之间的距离，因此`O(1)`之后的距离查询`O(n log n)`预处理是必不可少的。 

顶点按坚果数量分组。 虽然门槛`k`减小，值大于阈值的顶点进入活动集。 

活跃集总是代表`S(k) = {u : a_u > k}`。 我们逐步维护其直径端点。 插入新顶点时，直径改变的唯一可能方式是该顶点成为新直径的一个端点。 检查到当前端点的距离就足够了。 

对于每个阈值，我们测试可行性条件`diameter ≤ 2k`。 如果成立，我们将评估确切的成本公式并更新答案。 

该实现使用迭代 DFS 来避免长路径上的递归深度问题。

 ## 边缘情况

 考虑```
2 100 0
5 7
1 2
```每个门槛都是无关紧要的，因为吃饭的成本已经为零。 活动集直径逻辑仍然有效，但最小成本立即`0`。 该算法评估该候选者并返回正确答案。 

考虑```
2 1 10
100 0
1 2
```一个常见的错误是假设一次操作中所有 100 个螺母都移动了。 事实上，之后`k`第一个顶点仍然包含的操作`100-k`坚果。 幸存者集保持非空状态，直到`k=100`。 阈值模型准确地捕获了这一点，因为当且仅当一个顶点幸存下来`a_u > k`。 

考虑路径```
1-2-3-4-5
a = [1,1,1,1,1]
```在`k=0`，活动集直径为`4`, 违反`diameter ≤ 2k`。 在`k=2`，活动集变空并且条件成立。 该算法通过保持的直径自动检测过渡并返回最佳成本。
