 ## 解决方案
 ## 问题理解

 我们得到一个字符串形式的数字，并且必须以银行风格的货币格式打印它。 

格式化规则结合了几个独立的转换。 整数部分从右开始每三位数字必须包含一个逗号。 小数部分必须恰好包含两位数字。 如果原始数字的小数位少于两位，我们会追加零。 如果超过两位，我们只需截掉多余的数字而不进行四舍五入。 

负数使用括号而不是减号显示。 美元符号必须始终出现在数值之前，对于负值，它必须放在括号内。 

输入长度最多为 100 个字符，因此这纯粹是一个字符串操作问题。 不需要算术，使用浮点数实际上是危险的，因为我们必须截断数字而不是四舍五入。 由于输入很小，因此即使多次传递字符串也完全没问题。 任何线性时间解决方案都很容易足够快。 

一些边缘情况可能会悄悄地破坏粗心的实现。 

数字可能根本不包含小数点。 

输入：```
2012
```正确输出：```
$2,012.00
```如果我们盲目分裂`"."`如果不检查它是否存在，我们可能会崩溃或错误地生成空小数部分。 

小数部分必须被截断，而不是四舍五入。 

输入：```
1.999
```正确输出：```
$1.99
```使用浮点格式，例如`"{:.2f}"`会产生`$2.00`，这是错误的。 

输入中不可能出现类似零的负值。 该语句保证等于零的值永远不会有负号。 这很重要，因为符号是根据原始字符串确定的，而不是根据截断后的格式化值确定的。 

输入：```
-0.001
```这个输入是被问题禁止的，所以我们不需要对其进行特殊处理。 

另一个微妙的情况是整数部分非常短的数字。 

输入：```
12.3
```正确输出：```
$12.30
```粗心的逗号构建循环可能会意外地将逗号添加到小数字之前。 

大量的数据也需要仔细分组。 

输入：```
123456789
```正确输出：```
$123,456,789.00
```分组必须从右侧开始，而不是从左侧开始。 

## 方法

 暴力式解决方案将重复剥离整数部分的最后三位数字并向后构建答案。 由于输入大小很小，这已经可以有效地工作。 我们还可以逐个字符手动模拟十进制格式。 

主要的危险不是性能而是正确性。 一旦浮点转换进入解决方案，截断行为就变得不可靠。 例如，转换`"999999999999999999.999"`变成浮点数会立即失去精度。 即使是很小的值，例如`"1.999"`如果使用标准格式化函数，则会舍入而不是截断。 

关键的观察是问题中的每个规则都直接作用于文本表示。 我们永远不需要数值本身。 整数部分仅用逗号重新排列，小数部分作为文本填充或截断，并从第一个字符检测负数。 

这意味着最干净的解决方案是纯字符串处理：

 首先删除可选的减号。 

然后将剩余的字符串拆分为整数和小数部分。 

从右侧开始用逗号组格式化整数部分。 

将小数部分标准化为恰好两个字符。 

最后附加美元符号和可选的括号。 

整个算法在输入长度上是线性的，并且避免了每个精度问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解数字转换 | O(n) | O(n) | 由于舍入和精度错误 |
 | 最佳字符串处理解决方案 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取输入字符串。 
2. 通过测试第一个字符是否为负数来判断数字是否为负数`'-'`。 

我们必须单独记住这一点，因为减号在最终格式中消失并被括号取代。 
3. 如果数字为负数，则删除前导`'-'`。 
4. 将剩余字符串拆分为整数和小数部分。 

如果字符串包含小数点，则分割`"."`。 

否则，整个字符串是整数部分，小数部分从空开始。 
5. 将小数部分标准化为恰好两位数。 

如果它少于两个字符，则追加零，直到其长度变成两个。 

如果超过两个字符，则仅保留前两个字符。 
6. 用逗号格式化整数部分。 

以三个字符为单位从右向左遍历数字。 反转收集的块并用逗号将它们连接起来。 

从右侧分组至关重要，因为最低有效数字决定分组边界。 
7. 将格式化的货币字符串构建为：```
$<formatted_integer>.<fraction>
```8. 如果原始数字为负数，则将整个结果括在括号中。 
9. 打印最终的字符串。 

### 为什么它有效

 该算法直接独立地实现每个格式化规则。 

整数部分转换保留所有数字，并且仅从右侧每三个位置插入逗号，与规范完全匹配。 

小数归一化总是产生恰好两个数字，因为它要么截断多余的字符，要么附加缺失的零。 

符号处理是正确的，因为原始符号在任何修改之前都被存储，并且随后转换为括号一次。 

由于每个转换都是确定性的并且对于字符串的一部分来说是本地的，因此最终输出与每个有效输入所需的财务格式相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    negative = s[0] == '-'

    if negative:
        s = s[1:]

    if '.' in s:
        integer_part, fractional_part = s.split('.')
    else:
        integer_part = s
        fractional_part = ""

    fractional_part = (fractional_part + "00")[:2]

    groups = []

    i = len(integer_part)
    while i > 0:
        start = max(0, i - 3)
        groups.append(integer_part[start:i])
        i -= 3

    formatted_integer = ",".join(reversed(groups))

    result = f"${formatted_integer}.{fractional_part}"

    if negative:
        result = f"({result})"

    print(result)

solve()
```解决方案首先在修改字符串之前保留符号信息。 当减号从输出格式中消失时，这可以避免以后出现混乱。 

整数部分和小数部分之间的分割完全通过字符串完成。 程序中的任何位置都不会发生数字转换，这避免了溢出和不需要的舍入行为。 

线路```
fractional_part = (fractional_part + "00")[:2]
```是标准化小数部分的紧凑方法。 追加`"00"`保证字符串至少有两个字符，并且切片恰好保留两个字符。 这可以正确处理所有三种情况：```
""     -> "00"
"3"    -> "30"
"987"  -> "98"
```整数格式化循环从右到左处理数字，因为逗号组是相对于最低有效数字定义的。 每次迭代提取一组最多三位数字。 

使用`reversed(groups)`在用逗号连接之前将组恢复为正常的从左到右的顺序。 

括号仅添加在最后。 这保证了美元符号保留在其中，这是语句所要求的。

 ## 边缘情况

 考虑输入：```
1.999
```该算法将字符串拆分为整数部分`"1"`和小数部分`"999"`。 标准化后：```
("999" + "00")[:2]
```产生`"99"`。 不会发生舍入，因为算法从不以数字方式解释该值。 最终答案变成：```
$1.99
```这直接符合声明要求。 

现在考虑：```
12
```没有小数点，因此小数部分以空字符串开头。 标准化后：```
("" + "00")[:2]
```变成`"00"`。 整数部分少于四位，因此不插入逗号。 输出变为：```
$12.00
```这证实了算法正确处理丢失的小数部分。 

考虑一个大的分组数字：```
1234567890
```分组循环提取：```
890
567
234
1
```以相反的顺序。 反转列表会产生：```
1,234,567,890
```它正确地将右侧的数字分组。 

最后，检查负值：```
-5.2
```首先记录该符号，然后在格式化之前删除该符号。 归一化小数部分变为`"20"`，生产：```
$5.20
```最后添加括号：```
($5.20)
```这确认了符号处理逻辑在格式化后保持正确，与数值无关。
