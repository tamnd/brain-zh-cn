 ## 解决方案
 ## 问题理解

 这个问题中的底层对象并没有立即以干净的形式呈现。 剥离叙事后，核心结构是关于排列$n$元素和一种称为“愤怒”的量，它是在人们按某种顺序处理的过程中积累的。 每个排序都会产生一个整数值，即总愤怒，并且在所有排列中，我们获得这些值的多重集。 

隐藏在文本中的关键重新表述是，我们可以将每个排序编码为规范的数字表示，其中每个位置贡献一个独立的有界选择，而不是直接考虑排列。 具体来说，每个元素$i$贡献一个范围内的值，该范围仅取决于$i$，总愤怒变成了这些每个元素贡献的总和。 这消除了排列依赖性，并将其替换为独立选择集的乘积。 

一旦进行了这种转变，问题就变成了：我们有$n$独立列表，其中列表$i$包含来自的所有整数$0$到$i-1$，并且每个完整选择都从每个列表中精确选择一个值。 每次选择都会产生总和，我们感兴趣的是$k$-所有可能选择中最大的总和。 

语句片段中没有明确说明约束条件，但“指数级大多重集上的第 k 个元素”的存在强烈表明枚举所有配置是不可能的。 配置总数为$1 \cdot 2 \cdot \ldots \cdot n$，它呈阶乘增长。 即使对于中等$n$，暴力枚举所有和是不可行的，甚至对所有值进行排序也是不可能的。 这迫使我们采取一种懒惰地探索组合空间并首先优先考虑大金额的方法。 

朴素推理的一个常见失败案例是尝试对总和进行动态规划。 虽然总和范围可能看起来是可控的，但州的数量随着$O(n^2)$每个元素，但仍然没有直接产生$k$-th 最大值，无需额外的选择机制。 另一个陷阱是假设独立性允许贪婪地直接组合最高值； 这是因为在一个坐标中选择稍小的值可以解锁许多不同的组合。 

## 方法

 暴力方法会枚举每个列表中一个值的所有可能选择并计算结果总和。 这是正确的，因为它直接匹配多重集的定义，但它在复杂性上立即失败。 组合数为$n!$，所以即使$n = 15$已经产生了超过十亿个状态，使得枚举变得不可能。 

一种更结构化的观察是每个列表都已经排序，并且问题简化为从每个列表中选择一个元素来最大化总和或对总和进行排序。 这是一个经典的“排序列表中的 k 个最佳组合”问题。 暴力爆炸来自于探索所有组合，但关键结构是任何状态都可以通过调整单个坐标转变为更好或更差的状态。 这形成了一个图，其中节点是索引的元组，边通过递减一个坐标来移动。 

这使我们能够在组合空间上应用最佳优先搜索。 我们从最大可能的总和开始，然后通过一次减少一个坐标来重复生成下一个最佳候选。 优先级队列按照总和的递减顺序维护候选者，并且访问集可以防止重复。 这本质上是 Dijkstra 算法在隐式图上的 k 最佳状态模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举|$O(n!)$|$O(n!)$| 太慢了|
 | 组合的最佳优先搜索 |$O(k \cdot n \log k)$|$O(k \cdot n)$| 已接受 |

 ## 算法演练

 我们重新诠释每个立场$i$就像有一个排序列表一样$A_i = [0, 1, \dots, i-1]$。 为了方便起见，我们反转每个列表，使其变得递减，从而将初始状态与最大可能的总和对齐。 

我们用索引元组表示一个状态$(p_1, p_2, \dots, p_n)$， 在哪里$p_i$指示我们从列表中选择的元素$i$。 状态的值是以下各项的总和$A_i[p_i]$全面的$i$。 

然后我们进行如下操作。 

1. 构建每个列表$A_i$按降序排列，以便$A_i[0]$是最大值$i-1$。 这确保了初始状态对应于最大可能的总和。 
2. 用状态初始化优先级队列$(0, 0, \dots, 0)$采用反向索引形式，这意味着我们从每个列表中选取最大的元素。 相关总和是$\sum (i-1)$。 
3. 维护一个访问集以避免多次处理相同的索引元组。 这是必要的，因为不同的坐标递减序列可能导致相同的配置。 
4. 反复从优先级队列中提取和最大的状态。 每次提取都会按顺序给出下一个最大的未见总和。 
5. 当一个状态弹出时，通过减少一个坐标来生成邻居$p_i$如果可能的话加 1。 每个邻居对应于用该列表中下一个较小的值替换一个选定的值，这以尽可能最小的方式减少该坐标的总和。 
6. 将每个看不见的邻居及其计算出的总和推入堆中。 
7. 停止一次$k$- 状态被提取； 它的总和就是答案。 

这样做的原因是，每个有效配置都可以通过一系列独立的坐标递减从最大配置到达。 优先级队列确保在所有边界配置中，我们总是接下来扩展最大的剩余和，因此提取顺序与全局排名匹配。 访问集保证每个配置仅被考虑一次，从而防止通过不同路径对相同状态进行冗余探索。 

## Python 解决方案```python
import sys
import heapq
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    # Each list Ai = [0..i-1], we store it in decreasing order
    a = []
    for i in range(1, n + 1):
        a.append(list(range(i - 1, -1, -1)))

    # initial state: take index 0 from each list (maximum elements)
    start_idx = tuple([0] * n)
    start_sum = sum(a[i][0] for i in range(n))

    heap = [(-start_sum, start_idx)]
    seen = set([start_idx])

    cnt = 0

    while heap:
        neg_sum, state = heapq.heappop(heap)
        cnt += 1

        if cnt == k:
            print(-neg_sum)
            return

        for i in range(n):
            if state[i] + 1 < len(a[i]):
                new_state = list(state)
                new_state[i] += 1
                new_state = tuple(new_state)

                if new_state not in seen:
                    seen.add(new_state)
                    new_sum = -neg_sum - a[i][state[i]] + a[i][state[i] + 1]
                    heapq.heappush(heap, (-new_sum, new_state))

    print(0)

if __name__ == "__main__":
    solve()
```实现直接反映了概念模型。 每个状态都存储为索引元组，并且通过求和将堆用作最大优先级队列。 邻居生成步骤恰好更改一个坐标，这对应于用该列表中的下一个较小选项替换一个选定元素。 总和更新是增量完成的，而不是从头开始重新计算，这避免了$O(n)$每次转换重新计算。 

一个微妙的点是初始状态必须对应于所有为零的索引，因为每个列表都按降序存储。 这保证了起始最大配置的正确性。 

## 工作示例

 考虑$n = 3$。 列表是$A_1 = [0]$,$A_2 = [1,0]$,$A_3 = [2,1,0]$。 最大状态为$(0,0,0)$与总和$0 + 1 + 2 = 3$。 

如果$k = 1$，算法立即返回 3。 

如果$k = 2$，我们弹出$(0,0,0)$，然后生成邻居：

 改变索引 2 给出$(0,0,1)$与总和$0 + 1 + 1 = 2$,

 改变索引 1 给出$(0,1,0)$与总和$0 + 0 + 2 = 2$,

 更改索引 0 无效。 

堆现在包含两个总和为 2 的状态。第二次提取返回 2。 

| 步骤| 状态| 总和| 行动|
 | --- | --- | --- | --- |
 | 1 | (0,0,0) | (0,0,0) | 3 | 开始 |
 | 2 | (0,0,1) | (0,0,1) | 2 | 从索引 2 生成 |
 | 3 | (0,1,0) | (0,1,0) | 2 | 从索引 1 生成 |

 该跟踪表明该算法正确地按降序枚举总和，而不会丢失中间值。 

第二个例子$n = 2$,$A_1=[0]$,$A_2=[1,0]$: 状态是$(0,0)=1$,$(0,1)=0$。 提取的顺序是 1 然后 0，与预期排名匹配。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(k \cdot n \log k)$| 每个$k$提取的状态生成最多$n$邻居，每个堆操作成本$\log k$|
 | 空间|$O(k \cdot n)$| 我们存储最多$k$访问过的州，每个州的大小$n$|

 复杂性是通过仅探索顶部来驱动的$k$配置而不是全部$n!$的可能性，它很适合典型的约束条件，其中$k$最多是周围$10^5$。

 ## 边缘情况

 一个关键的边缘情况是当$n = 1$。 该算法仍然初始化单个列表，并且堆仅包含一种状态。 不发生邻居生成，并且立即返回答案。 这证实了基本情况不需要特殊处理。 

另一种情况是当$k$等于可达配置的总数。 在这种情况下，堆最终会耗尽所有状态并返回最后提取的值。 访问集确保即使状态之间存在多个路径，每个配置对排序只贡献一次。 

最后的边缘情况是多个坐标产生相同的总和。 堆可能包含具有相同值的不同状态，但正确性依赖于状态标识，而不是值的唯一性。 访问集可以防止重复，并且相等值之间的提取顺序不会影响正确性，因为所有相等值状态在多重集排名中以任何顺序都是有效的。
