 ## 解决方案
 ## 问题理解

 我们得到了一个位置值数组和一个查询列表。 每个查询指定数组的一个连续段。 对于每个段，我们查看其中的所有元素并确定最大值出现的位置。 如果多个位置共享最大值，则该问题隐含地需要一致的平局打破规则，通常是最左边或最小的索引。 

对于每个查询，我们都会在其段内记录这座“最高的山”的索引。 最终任务是计算对于数组中的每个位置，有多少查询选择该位置作为最大值的位置。 

因此，我们不是用最大值本身来回答每个查询，而是计算每个索引在所有查询间隔内成为 argmax 的频率。 

这些约束（大量查询和可能很大的数组大小）意味着通过扫描每个段来重新计算最大值会太慢。 一个简单的解决方案会在其范围内以线性时间检查每个查询，从而在最坏的情况下导致二次行为。 这立即超出了 Codeforces 问题的典型限制（最多 20 万个元素或查询）。 

当值重复时，会出现一个更微妙的问题。 如果存在相等的最大值，不一致的平局打破将改变计数分布。 正确的实现必须确保始终为相同的最大值选择相同的确定性索引。 

一个小例子就说明了这个问题。 假设数组是`[1, 3, 2, 3]`。 对于查询`[1, 4]`，索引 2 和 4 的值都是 3。如果我们总是选择最左边的最大值，则选择索引 2。 如果不小心实现，只要看到最大值而不跟踪位置就更新答案，可能会错误地选择索引 4，从而扭曲最终的频率计数。 

## 方法

 暴力方法独立处理每个查询。 对于查询范围`[l, r]`，我们扫描之间的所有元素`l`和`r`并跟踪最大值及其索引。 这是正确的，因为它直接遵循答案的定义。 然而，如果有`m`对大小数组的查询`n`，每个查询都会花费`O(n)`在最坏的情况下，导致`O(nm)`总工作量。 当两者`n`和`m`很大，这变得不可行。 

关键的观察是数组是静态的，我们只需要范围最大查询。 这允许预处理一个数据结构，该结构可以在对数甚至常数时间内回答“该段中的最大值是多少，以及它出现在哪里”。 数组上的稀疏表存储最大值及其索引，使我们能够计算任意查询范围的 argmax`O(1)`后`O(n log n)`预处理。 

一旦我们能够有效地回答每个查询，我们就不需要更新范围或维护任何动态结构。 我们简单地计算每个索引返回的次数作为最大值。 

最初的想法中提到的范围聚合和后缀累积对应于用频率数组和最终累积步骤替换重复的每个索引更新。 我们不进行昂贵的按范围传播，而是直接增加每个查询的选定索引。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(纳米) | O(1) | O(1) | 太慢了|
 | 稀疏表+计数| O((n + m) log n) | O((n + m) log n) | O(n log n) | O(n log n) | 已接受 |

 ## 算法演练

 ## 算法演练

 1. 在数组上构建支持范围最大查询的稀疏表。 每个条目都存储值及其索引，以便可以确定地解决关系。 存储索引的原因是最终答案取决于位置，而不是值。 
2. 预先计算对数，以便任何查询范围都可以分解为两个相等的二次幂长度的重叠区间。 这使得恒定时间查询成为可能。 
3.对于每个查询范围`[l, r]`，使用稀疏表检索该段中最大元素的索引。 此步骤取代了对该范围的显式扫描。 
4. 维护频率数组`cnt`， 在哪里`cnt[i]`代表有多少查询选择了索引`i`作为最大值。 
5.对于每个查询结果索引`p`, 增量`cnt[p]`一个。 这直接汇总了所选职位的所有贡献。 
6. 处理完所有查询后输出频率数组。 

### 为什么它有效

 每个查询根据确定性规则独立地选择一个索引：其范围内最大值的位置。 稀疏表保证该选择对于恒定时间内的每个查询都是正确的。 由于每个查询都为一个索引贡献了一个权重单位，因此累积每个索引的计数可以保留选择的精确分布。 查询之间不存在交互，因此独立计算结果的线性聚合就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_sparse(a):
    n = len(a)
    LOG = (n).bit_length()
    st = [[(0, 0)] * n for _ in range(LOG)]
    
    for i, v in enumerate(a):
        st[0][i] = (v, i)
    
    j = 1
    while (1 << j) <= n:
        length = 1 << j
        half = length >> 1
        for i in range(n - length + 1):
            left = st[j - 1][i]
            right = st[j - 1][i + half]
            if left[0] >= right[0]:
                st[j][i] = left
            else:
                st[j][i] = right
        j += 1
    
    return st

def query(st, l, r):
    length = (r - l + 1).bit_length() - 1
    left = st[length][l]
    right = st[length][r - (1 << length) + 1]
    if left[0] >= right[0]:
        return left[1]
    return right[1]

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    st = build_sparse(a)
    cnt = [0] * n
    
    for _ in range(m):
        l, r = map(int, input().split())
        l -= 1
        r -= 1
        p = query(st, l, r)
        cnt[p] += 1
    
    print(*cnt)

if __name__ == "__main__":
    solve()
```对于每个区间长度，稀疏表结构存储该区间中最大元素的索引。 在查询期间，范围被分成两个重叠的二次幂块，并比较它们预先计算的最大值。 返回较大值的索引。 

频率数组直接累加结果。 每个查询只贡献一个增量，因此循环后不需要进一步处理。 

打破平局时必须小心。 比较使用`>=`这样当值相等时，左边的区间获胜，确保确定性地选择较小的索引。 

## 工作示例

 考虑一个数组`a = [2, 1, 3, 3]`有疑问`[1,4]`,`[2,3]`， 和`[3,4]`。 

对于第一个查询`[1,4]`，最大值为`3`，出现在索引 3 和 4 处。平局规则选择索引 3。 

对于第二个查询`[2,3]`，该段是`[1,3]`，最大值位于索引 3 处。 

对于第三个查询`[3,4]`，两个索引都包含`3`，并选择最左边的索引 3。 

| 查询 | 范围 | 最大索引 | 碳纳米管状态 |
 | --- | --- | --- | --- |
 | 1 | [1,4]| 3 | [0,0,1,0] |
 | 2 | [2,3]| 3 | [0,0,2,0] |
 | 3 | [3,4]| 3 | [0,0,3,0]|

 此跟踪显示，由于相同的最大结构，所有查询一致解析为相同的索引。 

第二个例子使用`a = [5, 1, 4, 2]`有疑问`[1,2]`,`[1,3]`,`[3,4]`。 

| 查询 | 范围 | 最大索引 | 碳纳米管状态 |
 | --- | --- | --- | --- |
 | 1 | [1,2]| 1 | [1,0,0,0]|
 | 2 | [1,3]| 1 | [2,0,0,0] |
 | 3 | [3,4]| 3 | [2,0,1,0] |

 这表明重叠范围如何重复强化相同的主导指数。

 ## 边缘情况

 当所有元素都相等时，每个查询完全取决于平局打破。 对于像这样的数组`[5, 5, 5]`和一个查询`[1, 3]`，由于左偏合并，稀疏表始终返回索引 1。 重复查询只会在索引 1 处累积，从而产生严重倾斜的频率分布。 该算法可以正确处理这个问题，因为比较规则在每个合并步骤中强制执行确定性，而不仅仅是在查询时。 

对于单元素数组，无论输入如何，每个查询范围都会折叠到相同的索引。 为了`a = [42]`, 任意查询`[1,1]`始终返回索引 1，并且稀疏表退化为单层。 该算法仍然有效，因为查询逻辑从不假设最小范围长度大于 1。
