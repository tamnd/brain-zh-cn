 ## 解决方案
 ## 问题理解

 我们有几个独立的骰子，每个骰子都有自己的面值列表。 单个操作包括掷一些骰子，观察它们的结果，并决定哪些骰子在未来掷骰时保持活动状态以及哪些骰子永久锁定。 一旦骰子被锁定，其价值就被固定并影响最终结果。 该过程一直持续到所有骰子都被锁定为止，目标是最大化最终获得的预期总价值。 

核心困难在于，每个决定都取决于未来掷骰的分布，因为提前锁定骰子会冻结潜在的低值，而保持其活动状态允许进一步重新掷骰，但也会引入不确定性。 任务是计算每一步最优决策下的最优预期最终总和。 

输入描述了多个骰子，每个骰子都有一组可能的面值。 如果允许我们在每次掷骰后根据观察到的结果最佳地选择要锁定的骰子，则输出是可实现的最大预期总价值。 

从复杂性的角度来看，自然状态空间涉及锁定骰子的子集以及所有可能的掷骰结果。 这随着骰子的数量呈指数增长，并且当骰子的数量很大时，特别是当每个骰子具有多个面时，使得对子集的任何直接动态编程都不可行。 由于这种形式的 Codeforces 问题典型存在较大的约束，任何枚举子集或模拟滚动结果的解决方案都将超出时间限制。 

当人们试图仅根据骰子的平均值贪婪地锁定骰子时，就会出现一种微妙的失败情况。 例如，具有值的骰子`[1, 1, 100]`平均值很高，但过早锁定可能会错过重复重掷直到高值出现的机会。 相反，像模具一样`[50, 50, 50]`没有方差，因此延迟锁定不会带来任何好处。 忽略方差的天真贪婪策略会导致错误的期望值计算。 

当所有骰子具有相同的分布时，会出现另一种边缘情况。 在这种情况下，锁定决策的任何排序都应该产生相同的预期值，但基于排序的简单解决方案仍可能由于关系的破坏方式而引入人为偏差。 

## 方法

 蛮力观点将问题视为马尔可夫决策过程。 每个状态由哪些骰子仍然处于活动状态以及在活动骰子上观察到的当前值组成。 从每个状态，我们在观察掷骰后对要锁定哪些骰子的所有可能选择进行分支。 这种方法是正确的，因为它明确评估了所有可能的决策和结果序列。 然而，状态的数量随着骰子的数量呈指数增长，并且每个状态都会扩展到所有可能的面组合。 如果有`n`每个骰子都与`m`面，仅辊配置的数量是`m^n`，并且转变会进一步增加这一点，即使对于中等程度的人来说也是完全不可行的`n`。 

关键的观察结果是，通过关注每个骰子如何独立地对最终期望值做出贡献，然后以结构化方式组合这些贡献，可以在骰子之间解耦决策结构。 我们没有模拟所有联合结果，而是将这个过程重新解释为对所有骰子的所有面值进行排序，并以受控顺序逐步聚合它们的贡献。 这将配置上的组合爆炸转化为确定性值上的排序和合并问题。 

一旦我们对面值进行排序，我们就可以按升序处理它们，并维护有多少骰子已经贡献了高于阈值的值。 这将期望值计算变成了对有序事件的扫描，而不是对状态的分支过程。 骰子列表之间的合并步骤是关键的优化，用排序序列的线性组合代替指数枚举。

 ## 算法演练

 ### 1. 将所有骰子的所有面值提取到单独的排序列表中

 我们首先独立处理每个骰子并将其面值收集到一个数组中。 对每个骰子的值进行排序使我们能够稍后推断阈值，而无需重复扫描未排序的数据。 

### 2. 将所有排序列表合并为一个排序结构

 我们不是在模拟过程中反复比较骰子结果，而是对所有骰子值进行全局合并，同时保留每个值来自哪个骰子。 这确保我们可以按升序处理值，同时仍然有效地跟踪每个芯片的贡献。 

### 3. 按升序扫描值

 我们从最小到最大迭代合并列表。 对于每个值，我们从概念上将其视为骰子贡献变得相关的阈值。 这种排序至关重要，因为期望随着面值的增加而单调累积。 

### 4. 维护每个芯片的激活计数

 对于每个骰子，我们跟踪在扫描中已经遇到了多少个骰子的面。 这让我们可以计算在当前阈值下每个骰子存在多少有利结果。 骰子的贡献仅取决于其内部排序，而不取决于全局相互作用。 

### 5. 使用概率累积加权贡献

 在每一步中，我们都会计算骰子贡献等于或高于当前阈值的值的概率。 由于人脸值是均匀分布的，因此该概率与剩余未见过的人脸的比例成正比。 我们将此概率乘以所考虑的值并将其累加到最终期望中。 

### 为什么它有效

 该算法之所以有效，是因为每个骰子的贡献仅取决于其面值的排名顺序，而不取决于与其他骰子的联合交互。 通过对全球所有值进行排序，我们将问题转化为按升序评估所有可能阈值的贡献。 在每个阈值处，预期值的边际增加恰好对应于穿过该阈值的概率质量，并且将这些增量相加即可重建完整的期望，而不会重复计算或丢失配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    dice = []
    
    for _ in range(n):
        arr = list(map(int, input().split()))
        dice.append(sorted(arr))
    
    events = []
    for i in range(n):
        for v in dice[i]:
            events.append((v, i))
    
    events.sort()
    
    cnt = [0] * n
    sz = [len(d) for d in dice]
    
    ans = 0.0
    
    for v, i in events:
        cnt[i] += 1
        # probability mass contributed by this prefix position
        prob = cnt[i] / sz[i]
        ans += v * prob
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先读取每个骰子并对其面值进行排序，以便我们稍后可以将前缀解释为概率质量。 然后，我们将所有值展平为单个事件列表，并用其原始骰子标记每个值。 对此事件列表进行排序可确保我们按升序处理贡献。 

这`cnt[i]`数组跟踪模具中有多少个值`i`到目前为止在扫描中已经看到了。 除以`sz[i]`将其转换为概率，因为每张脸的可能性相同。 乘以当前值可累加该阈值跨越的预期贡献。 

一个常见的陷阱是忘记每个芯片对概率质量都有独立的贡献，因此混合全局计数而不是每个芯片计数会错误地耦合分布。

 ## 边缘情况

 一种重要的边缘情况是所有骰子都具有相同的值。 假设我们有两个骰子`[5, 5]`和`[5, 5]`。 每个事件都有相同的值，因此任何排序都应该产生相同的结果。 该算法处理所有四个事件，对称地增加概率，并累积相同的贡献，无论顺序如何。 自从`cnt[i] / sz[i]`两个骰子的最终分布相同，最终的总和是稳定的。 

另一种边缘情况是当一个芯片比其他芯片大得多时，例如`[1, 1000000]`旁边有许多小的固定骰子。 扫描确保大值仅在其概率质量累积后才起作用，从而防止过早的过度计数。 

最后一种边缘情况是具有一个面的单个芯片。 在这种情况下，`cnt/sz`总是`1`，算法简化为直接对所有值求和，这与确定性结果正确匹配。
