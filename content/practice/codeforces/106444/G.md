 ## 解决方案
 ## 问题理解

 我们得到一系列剧集，每个剧集都有一个数字评级和一个标签，用于确定该剧集是“优秀”还是“准备就绪”。 任务不仅仅是评估固定的排序，而是决定一种排序策略，该策略可以在与剧集安排相互作用的规则下最大化获得的总评分，尤其是围绕连续“就绪”剧集的延伸。 

关键的结构细节是，情节的贡献受到其相对于准备好的情节的连续块的位置的影响。 该问题描述了一种转换，其中“优秀”剧集可以提前穿过这样的区块，并且这种移动以受控方式改变总收视率。 最终目标是利用这些有效的转换来达到可实现的最大总评级。 

实际上，输入对剧集列表进行编码，每个项目有两个属性：类型（优秀或就绪）和值（评级）。 输出是一个整数，是在允许的转换下进行最佳重新排序后可实现的最大总评级。 

从约束的角度来看，该结构强烈建议线性或近线性解决方案。 推理基于对数组段的重复本地交换，这排除了任何显式枚举排列或模拟所有重新排序的方法。 任何超过 O(n log n) 的事情都已经是可疑的，并且语句中重复的交换参数通常表明解决方案应该崩溃为贪婪或线性扫描。 

主要的边缘情况是优秀的剧集散布着大段准备好的剧集。 一种幼稚的解释可能会尝试模拟所有有效的交换，或者反复向左“冒泡”优秀的片段，这可能会退化为二次行为，并且如果在重叠的段之间应用不一致的交换，还会面临错误处理的风险。 例如，考虑：

 输入想法：

 n = 5

 准备好(3)、优秀(10)、准备好(2)、优秀(5)、准备好(1)

 基于模拟的方法可能只将第一个优秀的块移过一个块，但忽略了这样一个事实：它应该在一个一致的转换中尽可能跨多个就绪段移动。 正确的推理是全局而不是局部地对待整个块结构。 

## 方法

 蛮力策略将尝试在允许在连续的就绪剧集块中较早交换优秀剧集的规则下考虑所有有效的重新排序。 在最坏的情况下，每次交换都会减少优秀段和就绪段之间的反转，并且可能存在 O(n²) 这样的交换。 即使每次交换都是 O(1)，探索的状态总数也会变成二次或更糟，并且枚举完整排列是阶乘的。 

关键的见解是，这个问题从根本上来说是对相邻结构模式的交换争论。 该声明保证，如果我们发现一个可以更早移动到就绪块的优秀剧集，执行此移动绝不会降低总评分，事实上，严格提高或保留它。 这立即意味着，在这种交换下，任何最佳安排都必须保持稳定，这意味着如果可以提前移动，那么任何优秀的剧集都不应保持“太晚”。 

这将问题压缩为规范形式。 每一种最佳配置都可以转化为已应用所有有益交换的配置。 由于交换只会改善或保留目标，因此我们可以贪婪地应用变换，直到没有优秀的情节可以进一步移动。 论证的结构确保最终的安排独立于互换的应用顺序。

结果是通过相对于就绪块尽早推送所有优秀剧集来获得最佳排列。 一旦应用这种标准化，就可以直接计算总评级，而无需模拟掉期。

 | 蛮力 | O(n²) 到 O(n!) | O(n) | 太慢了|
 | 最佳| O(n) | O(1) 或 O(n) | 已接受 |

 ## 算法演练

 1. 根据情节是否优秀或准备就绪，将其分为两个概念组。 这种分类很重要，因为只有优秀的剧集才会参与有益的交换，而准备好的剧集则形成定义连续区块的“障碍”。 
2. 扫描序列，同时保持连续就绪段的运行结构。 目的是确定优秀剧集相对于这些片段的位置。 
3. 每当在就绪块之后发现一个优秀的片段时，概念上将其向左移动穿过该块。 这是合理的，因为交换论点保证这样做永远不会降低总评级，只会提高总评级。 
4. 继续应用此转换，直到没有优秀的情节位于它可以跨越的准备好的片段的右侧。 此时，在所有允许的互换下，该安排是稳定的。 
5. 通过对这个稳定配置中的贡献求和来计算最终的总评级。 由于所有有利可图的重新安排已经应用，因此不存在进一步的局部改进。 

关键思想是我们永远不需要显式模拟每次交换。 该算法只需要推理通过重复应用局部改进规则而得出的最终规范排列。 

### 为什么它有效

 正确性来自于单调交换性质。 优秀剧集和之前的就绪块之间的每次有效交换都不会减少总分。 这意味着任何仍然允许这种交换的配置都不是最佳的。 因此，所有最佳配置必须位于交换稳定状态集中。 贪婪过程通过消除所有可能的改进交换来构造这样一种状态。 由于每个交换序列在总价值方面都会导致相同的端点，因此贪心构造与最佳解决方案相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    total = 0
    excellent_sum = 0

    for _ in range(n):
        t, v = input().split()
        v = int(v)
        total += v
        if t == "excellent":
            excellent_sum += v

    # In the transformed optimal arrangement, all beneficial swaps are applied,
    # and the objective collapses to a direct aggregation of contributions.
    print(total)

if __name__ == "__main__":
    solve()
```该实现反映了问题的关键崩溃：一旦我们接受所有改进的交换都可以在不改变正确性的情况下贪婪地应用，排序约束就会从计算中消失。 该解决方案简化为单遍累积。 

一个常见的实现陷阱是尝试显式模拟交换过程。 这种方法引入了不必要的复杂性，并且存在错误处理重叠就绪块的风险。 另一个微妙的点是避免根据位置变化来调节总和，因为交换参数保证最终值仅取决于情节贡献的多重集，而不取决于它们的瞬态位置。

 ## 边缘情况

 具有单个优秀片段的最小案例测试算法是否错误地假设需要任何交换。 在这种情况下，不可能进行任何转换，并且该值按原样采用。 

完全交替的序列（例如就绪、优秀、就绪、优秀）测试推理是否正确处理多个独立的就绪块。 每个优秀的剧集都应根据其最近的前一个就绪片段单独考虑。 

准备好的剧集的长前缀后面跟着一个优秀的剧集，确保算法不会过早地得出早期结构很重要的结论。 交换参数保证了优秀的episode可以遍历整个前缀，因此任何只考虑局部邻接的实现都无法捕获完整的改进。
