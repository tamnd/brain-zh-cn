 ## 解决方案
 ## 问题理解

 我们给出一个写成正规分数的有理数`p / q`，以及另一个写为有限连分数的数字。 

连分数的形式为：$$a_1 + \frac{1}{a_2 + \frac{1}{a_3 + \dots}}$$我们必须确定这两种表示是否描述相同的有理数。 

连分数长度最多为 90，这个长度很小。 值本身可以大到$10^{18}$，所以算术必须仔细进行。 Python 自然地处理任意大的整数，这使得实现比固定宽度整数语言安全得多。 

直接浮点比较在这里是完全不可靠的。 连分数可以表示巨大的分子和分母，而浮点舍入会悄悄破坏等式检查。 

最危险的边缘情况来自中间部分。 

考虑这个输入：```
3 2
2
1 2
```连分数等于：$$1 + \frac{1}{2} = \frac{3}{2}$$正确答案是`YES`。 

使用浮点的粗心实现可能会计算出类似的结果`1.4999999999999998`并错误地拒绝平等。 

当连分数的长度为 1 时，会出现另一个微妙的情况：```
5 1
1
5
```连分数很简单`5`。 根本不存在嵌套分母。 盲目地假设至少两项的代码要么崩溃，要么产生错误的结果。 

一种更棘手的情况来自于太晚减少分数。```
1000000000000000000 1
2
999999999999999999 1
```连分数等于：$$999999999999999999 + \frac{1}{1} = 1000000000000000000$$中间值变得非常大。 如果在简化之前实现倍增，则具有 64 位溢出的语言将会失败。 Python 避免了溢出，但算法仍应保持数学上的干净。 

## 方法

 蛮力的想法很简单：将连分数明确地计算为分子和分母，然后将其与`p / q`。 

我们可以从后面重建分数。 假设我们已经知道后缀的值`x / y`。 然后添加上一项`a[i]`将其转换为：$$a_i + \frac{y}{x} = \frac{a_i x + y}{x}$$这是可行的，因为每个有限连分数都代表一个有理数。 

暴力版本使用任意精度算术重复构造分数。 自从`n ≤ 90`，即使是巨大的整数仍然是可以管理的。 该算法仅执行线性多次算术运算。 

关键的观察是我们实际上根本不需要计算十进制值或模拟除法。 连分数与欧几里得算法紧密相连。 

认为：$$\frac{p}{q} = a_1 + \frac{r}{q}$$然后：$$a_1 = \left\lfloor \frac{p}{q} \right\rfloor$$余数递归地定义了连分数的其余部分。 

这意味着我们可以直接将给定序列与欧几里得分解进行比较`p / q`。 

每一步：

 1. 下一个连分数系数必须等于`p // q`。 
2.然后我们替换`(p, q)`和`(q, p % q)`。 

这正是欧几里得算法。 

蛮力构造已经顺利通过了，因为`n`只有 90，但欧几里得解释更清晰、更简单，并且避免显式构造巨大的中间分子。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力重建 | O(n) | O(1) | O(1) | 已接受 |
 | 欧几里得比较 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 阅读`p`和`q`。 
2. 读取连分数序列`a`。 
3. 对于每个值`x`按顺序：

 检查是否`p // q`等于`x`。 

如果它们不同，则表示不能相等，因此打印`NO`。 
4. 更换`(p, q)`和`(q, p % q)`。 

这反映了连分数的递归结构。 去掉整数部分后，剩下的小数变为：$$\frac{q}{p \bmod q}$$5. 处理完所有系数后，验证欧几里得过程是否准确完成。 

剩余的分母必须为零。 如果不是，则连分数结束得太早。 
6. 打印`YES`如果所有检查都成功，否则打印`NO`。 

### 为什么它有效

 有限连分数正是由欧几里得算法产生的商序列`(p, q)`。 

在每次迭代时：$$p = q \cdot \left\lfloor \frac{p}{q} \right\rfloor + (p \bmod q)$$整数商成为下一个连分数系数。 余数定义下一个递归分数。 

由于欧几里得算法唯一地将有理数分解为连分数系数，因此匹配每个商可以保证相等。 任何不匹配都意味着表示的数字不同。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    p, q = map(int, input().split())

    n = int(input())
    a = list(map(int, input().split()))

    for x in a:
        if q == 0:
            print("NO")
            return

        if p // q != x:
            print("NO")
            return

        p, q = q, p % q

    if q == 0:
        print("YES")
    else:
        print("NO")

solve()
```其实现直接遵循欧几里得算法。 

循环将每个连分数系数与当前整数商进行比较`p // q`。 如果它们甚至有一次不同，平等是不可能的。 

消耗一个系数后，我们使用以下方法进入下一个剩余状态：```
p, q = q, p % q
```这种变换是连分式递归的核心。 

最后的检查很微妙，很容易被忽视。 我们必须确保分数展开恰好在欧几里得算法终止时结束。 如果`q != 0`处理完所有系数后，序列太短。 

守卫：```
if q == 0:
```循环内部可防止在连分数比欧几里得分解长的畸形情况下被零除。 

Python 整数会自动扩展到任意大小，因此即使值远远超出了范围，我们也不必担心溢出$10^{18}$。

 ## 边缘情况

 考虑单元素连分数：```
5 1
1
5
```该算法开始于`p = 5`,`q = 1`。 

商为：$$5 // 1 = 5$$匹配唯一的系数。 然后：$$(p, q) = (1, 0)$$循环结束并且`q == 0`，所以答案是`YES`。 

这个案例证实了该实现正确地处理了连续分数，没有递归部分。 

现在考虑一个过早结束的序列：```
8 3
1
2
```第一个商是：$$8 // 3 = 2$$哪个匹配。 状态变为：$$(p, q) = (3, 2)$$该序列已经用尽，但是`q != 0`。 欧几里得过程还有剩余项，所以答案一定是`NO`。 

这验证了最终终止检查。 

最后，考虑一个太长的序列：```
2 1
3
2 1 1
```处理后系数`2`，状态变为：$$(p, q) = (1, 0)$$该算法还有更多系数需要读取。 自从`q == 0`，除法是不可能的，答案是立即的`NO`。 

这可以防止无效的额外条款被意外接受。
