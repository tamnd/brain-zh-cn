 ## 解决方案
 ## 问题理解

 我们收到了一系列短篇小说，分为两种类型：关于小猫的故事和关于小狗的故事。 有`c`小猫的故事和`d`总共有小狗故事。 目标是建立`n`卡通系列的剧集，其中每个故事必须仅使用一次，并且每个剧集必须包含相同数量的故事。 

每集还必须满足两个局部约束：它必须至少包含`a`小猫的故事，至少`b`小狗的故事。 

所以我们本质上是试图分割多个集合`c + d`两种颜色的物品分为`n`相同大小的垃圾箱，其中每个垃圾箱对两种颜色都有最小配额，并且所有项目必须仅使用一次。 

关键的困难在于这些约束以全局方式相互作用。 即使总数看起来可行，但由于可分性和每集下限，在尊重每个 bin 最小值的同时均匀分配它们可能会失败。 

输入大小可达`10^18`，这立即消除了任何尝试模拟分配或搜索每集分配的方法。 任何解决方案都必须将问题减少到恒定数量的算术检查。 

一个天真的但诱人的错误是假设如果总计数满足`c >= n * a`和`d >= n * b`，那么答案总是肯定的。 这是错误的，因为在保证最低限度后，剩余的故事仍然必须在各集之间均匀分布，而不破坏每集的结构。 

当分配最低要求后剩余的故事无法均匀分割时，就会出现第二种微妙的边缘情况。 即使两个总数都足够大，对剩余分布的可分性限制也会破坏可行性。 

## 方法

 强力解释会尝试将故事分配构建为`n`情节明确。 人们可以想象一集一集地填充，至少贪婪地分配`a`小猫和`b`每集讲小狗故事，然后分发剩下的故事。 这很快就变得不可行，因为可能的分布数量与`n`， 和`n`可以大到`10^18`。 

关键的观察结果是，每个情节在结构上都没有区别：所有情节都具有相同的大小，并且只有聚合计数才重要。 这减少了从每集构建到检查我们是否可以选择有效的集大小的问题`k`，然后将这两种类型的故事分成`n`大小组`k`。 

让`k`是每集的故事数。 那么我们必须有`k * n = c + d`， 所以`k = (c + d) / n`。 这已经是一个严格的可行性条件：总故事数必须能被`n`。 

一次`k`是固定的，每集必须至少包含`a`小猫和`b`小狗的故事，所以我们需要`k >= a + b`。 这是因为每个情节必须同时满足两个下限。 

现在唯一剩下的问题是我们是否可以精确分配`c`小猫的故事和`d`小狗的故事`n`大小的箱子`k`每个，尊重每个箱的下限。 预订后`a`小猫和`b`每个垃圾箱里有一只小狗，我们剩下：`c - n * a`额外的小猫故事和`d - n * b`额外的小狗故事。 

这些剩余物必须任意分配`n`bins，但每个bin最多可以接受`k - a - b`额外的故事。 只要总数匹配且不超过可用容量，此功能就会自动运行，这是在以下情况下得到保证的：`k`计算正确并且满足最小约束。 

因此，可行性减少到一些算术检查。

 ## 算法演练

 我们直接从有效分区的结构中导出条件。 

1. 计算故事总数`S = c + d`。 如果`S`不能被整除`n`，没有办法将所有故事分成`n`相同的情节，所以我们立即停止。 
2. 定义剧集大小`k = S / n`。 这是每个剧集唯一可能的大小，因为所有剧集必须相等并且必须使用所有故事。 
3. 检查每集的最低要求：每集必须至少包含`a + b`故事，因为它至少需要`a`小猫的故事和`b`小狗的故事。 如果`k < a + b`，那么即使是最小的有效情节也会违反约束，因此我们拒绝。 
4. 检查小猫分配的可行性：小猫故事总数必须足以提供`a`每集，所以`c >= n * a`。 
5.同样，小狗的故事必须满足`d >= n * b`。 
6. 如果所有条件成立，则可以进行分区； 否则是不可能的。 

步骤 4 和 5 背后的原因是最小约束是每集的，而不是全局的。 每集独立消耗至少`a`小猫和`b`小狗的故事，所以总数必须支持`n`重复这些要求。 

### 为什么它有效

 任何有效的构造都必须准确分配`k`每集都有故事，因此完全可分是必要的。 一旦这个问题解决了，每一集都有一个强制性的基本成本`a`小猫和`b`小狗的故事。 从总数中减去这个基数就留下了一个免费的故事池，可以在剧集之间任意分配。 这些约束确保该空闲池永远不会为负，并且永远不会超过每集的可用容量，因此除了这些算术检查之外，不存在进一步的结构限制。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
a = int(input())
b = int(input())
c = int(input())
d = int(input())

total = c + d

if total % n != 0:
    print("No")
else:
    k = total // n
    if k < a + b:
        print("No")
    elif c < n * a:
        print("No")
    elif d < n * b:
        print("No")
    else:
        print("Yes")
```该解直接编码必要的算术条件。 可分割性检查确保存在相同的剧集大小。 比较`k < a + b`强制每个情节可以同时满足每种类型的最小值。 最后两个不等式确保全局计数足以满足所有的每集配额`n`剧集。 

所有算术都适合 64 位整数范围，因此 Python 可以安全地处理它，而无需担心溢出。

 ## 边缘情况

 一个关键的边缘情况是当`n = 1`。 在这种情况下，整本书就变成了一个单集，因此唯一的要求是总数本身满足最小约束。 该算法简化为检查是否`c >= a`和`d >= b`，这是正确执行的，因为`k = c + d`和`k >= a + b`仅当两个总数都足够时，才意味着可行性。 

另一个边缘情况是当`a = 0`或者`b = 0`。 然后，其中一个约束消失，并且解决方案正确地简化为仅检查总整除性和剩余约束。 算术条件自然简化，无需特殊处理。 

当总数完全符合每集的最低要求时，就会出现最后一个微妙的情况，没有灵活性。 例如，如果`c = n * a`和`d = n * b`，那么每一集都被迫恰好包含最小值。 该算法接受这一点是因为`k = a + b`，并且每个类型的总数完全匹配，确保严格但有效的分区。
