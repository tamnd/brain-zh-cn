 ## 解决方案
 ## 问题理解

 我们得到一个单词序列，每个单词都带有一个可以是正数或负数的整数值。 我们最多可以插入`k`逗号，它将序列分成连续的段。 每个片段都会对总分做出贡献，但贡献的符号取决于我们是否在该片段周围放置特殊词“нельзя”。 

每个段都可以通过在逗号之前和/或之后插入“нельзя”来标记为“翻转”，如语句中所述，但最终效果很简单：每个段要么正常添加，要么减去，我们通过放置规则间接控制此选择。 每个片段最多可以包含一个“нельзя”的约束意味着每个片段的贡献独立地变得积极或消极，但我们不能任意地为单个单词分配符号，只能为整个片段分配符号。 

所以真正的结构是：我们将数组最多划分为`k+1`连续的段，以及每个段`l..r`贡献要么`+sum(a[l..r])`或者`-sum(a[l..r])`。 我们希望最大化所有部分的总和。 

约束条件`n ≤ 500`立即表明二次或三次动态规划是可行的。 任何像指数分裂这样的事情都是不可能的，因为分段的数量像组合爆炸一样增长，大约`2^n`。 

天真的思维的一个微妙的失败案例是假设我们应该只将“нельзя”放在具有负数的段上。 这是不正确的，因为翻转一个段会改变它的符号，所以有时我们想故意将正和段设为负值，如果这样可以在有限的削减下实现更好的全局结构。 

另一种失败模式是尝试贪婪分割：选择最佳的局部分割位置。 例如，选择局部最佳的正块可以迫使剩余元素进入更差的配置，并且符号选择在全局范围内耦合片段。 

## 方法

 暴力解决方案将枚举将数组分割为最多的所有方法`k+1`段，然后为每个段分配一个符号。 即使忽略符号分配，分区的数量也是指数级的。 为了`n = 500`，这是完全不可行的。 

一个更结构化的观察是，一旦我们固定了分段边界，唯一剩下的自由就是每个分段是正还是负。 然而，这些选择与总和以线性方式相互作用，因此我们可以将它们折叠到 DP 状态。 

关键的见解是将其视为前缀上的间隔 DP：对于每个前缀`1..i`，并且对于给定数量的细分，我们跟踪可实现的最佳值。 转换考虑最后一个段结束于`i`，从某个开始`j+1`。 该部分的贡献是`+(prefix[i] - prefix[j])`或者`-(prefix[i] - prefix[j])`。 这减少了每次在两个线性形式之间进行选择的转换。 

该结构成为经典的“带有前缀和和符号选择的分区 DP”，可解为`O(n^2 k)`。

 | ---| ---| ---| ---|
 | 暴力分区| O(2^n) | O(2^n) | O(n) | 太慢了|
 | 段和端点上的DP | O(n^2k) | O(n^2k) | O(nk) | O(nk) | 已接受 |

 ## 算法演练

 我们预先计算前缀和，以便可以在 O(1) 内获得任何段和。 让`pref[i]`是第一个的总和`i`价值观。 

我们定义一个 DP 表，其中`dp[t][i]`表示精确使用可达到的最大分数`t`涵盖第一个部分的部分`i`元素。 

我们还包括不使用所有的可能性`k`通过取所有有效值中的最大值来削减`t`。 

### 步骤

 1.构建前缀和数组`pref`在哪里`pref[i] = a[1] + ... + a[i]`。 这允许恒定时间段总和查询。 
2. 对除`dp[0][0] = 0`，表示零段覆盖零个元素。 
3. 迭代段数`t`从`1`到`k+1`。 每个段计数对应`t-1`逗号。 
4. 对于每个端点`i`,尝试所有可能的先前分割点`j < i`。 最后一段是`(j+1 .. i)`。 
5. 计算分段总和`S = pref[i] - pref[j]`。 该部分可以贡献`+S`或者`-S`。 所以我们采取`max(S, -S)`，即`|S|`。 
6. 过渡：`dp[t][i] = max(dp[t][i], dp[t-1][j] + abs(pref[i] - pref[j]))`。 
7. 答案是其中的最大值`dp[t][n]`为了`t ≤ k+1`。 

### 为什么它有效

 关键的不变量是，每个有效的构造恰好对应于一个分段划分，并且每个分段独立地贡献其总和或负总和。 DP 枚举每个前缀的所有可能的最后分段，并且对于每个这样的分段，它已经假设了较早前缀的最佳解决方案。 由于绝对值独立地捕获每个段的最佳符号选择，因此我们永远不需要重新审视之前的决策。 这确保了每个有效配置通过某种转换序列精确地表示一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    NEG = -10**18
    dp = [[NEG] * (n + 1) for _ in range(k + 2)]
    dp[0][0] = 0

    for t in range(1, k + 2):
        for i in range(1, n + 1):
            best = NEG
            for j in range(i):
                if dp[t - 1][j] == NEG:
                    continue
                seg = pref[i] - pref[j]
                best = max(best, dp[t - 1][j] + abs(seg))
            dp[t][i] = best

    ans = 0
    for t in range(1, k + 2):
        ans = max(ans, dp[t][n])

    print(ans)

if __name__ == "__main__":
    solve()
```前缀和数组是核心简化，消除了重复的 O(n) 段和计算。 DP层`t`计算到目前为止使用了多少段。 内部转换显式尝试所有分割点，这是有效的，因为`n ≤ 500`。 

使用`abs(seg)`独立于其他片段对该片段的“нельзя”的最佳可能位置进行编码，因为每个片段都可以翻转或不翻转，而不会影响其他片段。

这表明，即使总和为零，分段加符号选择也可以创造正值。

 ## 边缘情况

 单个大负块测试算法是否正确使用符号翻转而不是避免分割。 例如，`[-10, -20, -30]`有足够的段应该产生`60`，DP 通过获取整个片段并将其翻转一次来实现这一点。 

完全正数数组会检查不必要的分割不会改善答案。 为了`n=500`积极和小`k`，最优策略崩溃为采用大的绝对分段，并且 DP 自然更喜欢全范围分段而无需人为分割，因为绝对值保留了大的连续总和。 

交替符号测试分段和绝对值之间的相互作用。 输入如`[100, -100, 100, -100]`确保 DP 不依赖于局部最大值，而是将元素分组为片段，其总大小在潜在的符号翻转后最大化。
