 ## 解决方案
 ## 问题理解

 对于固定整数$k$，查看斐波那契数列并标记斐波那契值可整除的每个位置$k$。 

例如，当$k=2$：$$1,1,\mathbf{2},3,5,\mathbf{8},13,21,\mathbf{34},\dots$$标记的位置是$3,6,9,\dots$。 

定义$G(n,k)$作为的位置$n$-第一个标记的斐波那契数。 我们被给予$n$和$k$，并且必须计算$G(n,k)$模数$10^9+7$。 

主要的困难在于$n$可以大到$10^{18}$。 我们无法生成斐波那契数列或一项一项地计算可整除的项。 甚至一个$O(n)$算法是完全不可能的。 

另一个重要的限制是$k \le 10^5$，以及所有的总和$k$跨测试用例的值最多是$10^6$。 这强烈表明我们应该花费大约$O(k)$每个测试用例工作并利用一些仅依赖于的结构$k$。 

出现微妙的边缘情况时$k=1$。 每个斐波那契数列都可以被$1$，所以标记的位置就是$1,2,3,\dots$。 因此$G(n,1)=n$。 任何假设可分性事件稀疏的解决方案都可能在这里失败。 

例如：```
Input:
1
5 1
```正确答案是：```
5
```另一个容易犯的错误是搜索$n$- 可直接整除的斐波那契数。 考虑：```
Input:
1
1000000000000000000 2
```答案存在于一个索引处$3 \times 10^{18}$。 一一模拟位置是没有希望的。 

第三个陷阱是忘记最终答案需要模数$10^9+7$。 实际指数$G(n,k)$可能远远大于 64 位限制$n$是巨大的。 必须使用模运算来应用模数，而不是构造完整值。 

## 方法

 最直接的想法是生成斐波那契数模$k$，检查每一项是否能被整除$k$，并统计出现了多少个这样的位置。 一旦计数达到$n$，我们输出当前索引。 

这是正确的，因为整除$k$仅取决于斐波那契值模$k$。 问题是$n$可以是$10^{18}$，所以我们可能需要处理$10^{18}$职位。 这远远超出了可能的数量级。 

关键的观察是斐波那契数模$k$是周期性的。 顺序$$(F_i \bmod k)$$称为皮萨诺序列。 由于每个状态都是由对决定的$$(F_i \bmod k,\; F_{i+1} \bmod k),$$只有$k^2$可能的状态。 最终一个状态会重复，一旦一个状态重复，整个序列就会重复。 

事实上，斐波那契数列模$k$总是返回到起始对$(0,1)$。 这个周期的长度就是皮萨诺周期。 

在一个时期内，职位$F_i \equiv 0 \pmod k$形成重复的图案。 让第一个这样的位置是$z$。 斐波那契数列的一个经典属性表明，每个索引都可以整除$z$还给出了$k$，并且没有更小的正指数可以做到。 因此，所有可分割的职位都是$$z,\;2z,\;3z,\dots$$这$n$因此，第 - 个可整除的斐波那契数位于位置$$n \cdot z.$$整个问题简化为寻找最小的正索引$z$这样$$F_z \equiv 0 \pmod k.$$自皮萨诺时期以来$k \le 10^5$至多是$6k$，我们可以通过模拟斐波那契数模来找到这个指数$k$直到出现第一个零。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(G(n,k))$|$O(1)$| 太慢了|
 | 最佳 |$O(k)$每个测试用例|$O(1)$| 已接受 |

 ## 算法演练

 1. 让`MOD = 1_000_000_007`。 
2. 对于测试用例$(n,k)$，生成斐波那契数模$k$。 
3. 从配对开始$(1,1)$，对应于$F_1$和$F_2$。 
4. 重复计算下一个斐波那契余数模$k$，同时跟踪其指数。 
5.第一个索引$z$残差变为零的地方是满足的最小正索引$F_z \equiv 0 \pmod k$。 

这个指标通常被称为显灵等级$k$。 
6. 每个斐波那契数都可以被$k$发生在一个指数的倍数处$z$。 
7. 的$n$因此，第一个可整除的斐波那契数位于索引处$n \cdot z$。 
8. 输出$$(n \bmod MOD)\cdot(z \bmod MOD)\bmod MOD.$$### 为什么它有效

 让$z$是最小的正索引$F_z \equiv 0 \pmod k$。 

标准斐波那契整除性属性指出$$\gcd(F_a,F_b)=F_{\gcd(a,b)}.$$利用这一事实，我们可以证明，如果$F_m$可以整除$k$， 然后$z$划分$m$。 否则$F_{\gcd(z,m)}$也可以被整除$k$，与极小性相矛盾$z$。 

相反，斐波那契数列满足$$F_z \mid F_{tz}$$对于每个正整数$t$。 自从$F_z$已经可以被整除$k$， 每一个$F_{tz}$可以整除$k$以及。 

因此，可整除的位置恰好是$$z,2z,3z,\dots$$和$n$-th 这样的位置是$nz$。 该算法发现$z$并计算该值的模$10^9+7$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def first_zero_index(k):
    if k == 1:
        return 1

    a, b = 1 % k, 1 % k
    idx = 2

    while True:
        a, b = b, (a + b) % k
        idx += 1

        if b == 0:
            return idx

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, k = map(int, input().split())

        z = first_zero_index(k)
        ans.append(str((n % MOD) * (z % MOD) % MOD))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```功能`first_zero_index`搜索第一个其值可被整除的斐波那契指数`k`。 变量`a`和`b`始终表示两个连续的斐波那契余数模`k`。 

索引开始于`2`因为`a`和`b`最初对应于`F1`和`F2`。 每次转换后，`b`成为下一个斐波那契值，所以当`b == 0`，当前值`idx`正是所需的索引。 

特殊情况`k == 1`单独处理，因为每个斐波那契数都可以整除`1`，使得答案索引等于`1`。 

最后的乘法立即使用模运算。 自从`n`可能大到`10^18`，计算模首先使所有值保持较小并避免不必要的大整数。

 ## 边缘情况

 考虑：```
1
5 1
```每个斐波那契数列都可以被`1`。 算法立即返回`z = 1`。 答案就变成了`5 × 1 = 5`。 不需要生成序列。 

考虑：```
1
1 2
```斐波那契数列模数`2`是：```
1, 1, 0, 1, 1, 0, ...
```第一个零出现在索引处`3`， 所以`z = 3`。 答案是`1 × 3 = 3`。 这验证了第一个可整除的斐波那契数不一定位于索引处`1`。 

考虑：```
1
1000000000000000000 2
```相同`z = 3`被发现。 该算法计算$$(10^{18} \bmod 10^9+7)\cdot 3 \bmod 10^9+7$$无需构建庞大的索引$3 \times 10^{18}$。 这正是最后应用模运算的原因。
