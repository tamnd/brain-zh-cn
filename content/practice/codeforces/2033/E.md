 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 的数字排列。 我们可以反复交换任意两个位置。 执行一些交换后，我们希望排列满足每个索引 i 上的结构条件。 

在每个位置 i，该值要么已经位于其自己的位置，即 p[i] = i，要么与其正确位置形成相互配对，即如果 p[i] = x，则 p[x] 必须等于 i。 因此每个元素要么是一个不动点，要么是 2 循环的一部分。 最终安排中不再允许循环。 

任务是计算将给定排列转换为满足此条件的任何排列所需的最小交换次数。 

限制因素在这里非常重要。 所有测试用例的总 n 最多为 10^6，这排除了每个测试的任何二次方。 任何尝试通过扫描阵列来模拟交换或重复修复周期的解决方案都会失败。 每个测试用例我们需要一种线性或近线性分解方法。 

天真的思维的一个微妙的失败案例是假设每个周期都可以用固定公式独立修复，而不考虑互换如何在全球范围内相互作用。 例如，在像 [2, 3, 1] 这样的 3 周期中，人们可能会错误地认为它可以在 1 次交换中修复，但实际上需要 2 次交换才能将其分解为有效的固定点或 2 周期。 

另一个微妙的情况是循环的混合，例如不同长度的多个不相交的循环。 每个周期的贪婪局部修复仍然必须在整个结构上正确求和。 

## 方法

 直接的暴力方法将尝试模拟交换，直到排列变得有效。 每次交换后，我们都会扫描所有索引并检查每个位置是否满足条件。 每次扫描的成本为 O(n)，在最坏的情况下，我们可能需要 O(n) 次交换，导致每个测试用例的时间为 O(n^2)，这对于 n 高达 10^6 来说太大了。 

关键的观察结果是最终的结构受到极大的限制：排列图中的每个连接的组件必须成为固定点或固定点对。 这立即表明按照排列周期进行工作。 

每个排列都可以分解为不相交的循环。 在长度为 k 的循环内，我们必须决定需要多少次交换才能将其转换为有效结构。 关键的见解是，互换不会混合周期，除非我们故意打破它们，因此每个周期对答案都有独立的贡献。 

对于长度为 1 的循环，不需要任何东西。 对于长度为 2 的循环，它已经作为相互对有效。 对于任何长度 k ≥ 3 的循环，我们必须使用交换将其分成有效对和固定点。 最佳策略是使用 k - 1 次交换结构来减少每个此类循环，但更准确地说，在从交换分解中出现最佳配对行为后，长度为 k 的每个循环都贡献了 Floor((k - 1) / 2) 次交换。 

这个问题相当于计算需要多少次交换才能将每个周期转换为一组 1 周期和 2 周期。 每次交换最多可以修复循环内两个错位的元素，这直接导致配对解释。 

分解成周期后，我们累积每个周期的成本。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 循环模拟/暴力交换| O(n^2) | O(n^2) | O(n) | 太慢了|
 | 循环分解计数对| O(n) | O(n) | 已接受 |

 ## 算法演练

1. 构建一个已访问数组并迭代从 1 到 n 的所有索引。 每个未访问的索引都会开始新的循环遍历。 
2. 从该索引开始遍历排列，直到返回到访问过的节点。 收集周期的大小。 此步骤隔离独立的结构组件，这是必要的，因为一个周期内的交换不会影响另一个周期。 
3. 对于每个发现的循环，计算其对答案的贡献。 如果周期长度为 1 或 2，则贡献 0 次交换。 如果循环长度 k ≥ 3，则贡献Floor((k - 1) / 2)。 这来自于使用交换在周期内优化配对元素，其中每次交换以最佳可实现的排列解决了两个错位的位置。 
4. 对所有周期的贡献求和并输出结果。 

### 为什么它有效

 排列可以唯一地分解为不相交的循环，并且交换仅影响循环内的元素，除非明确用于合并循环。 然而，合并循环永远不会提高最优性，因为目标结构也会分解为独立的不动点和 2 个循环。 因此每个原始循环都可以独立求解。 

在长度为 k 的循环内，我们能做的最好的就是将其转换为有效的不动点和 2 个循环。 每次交换最多可以减少 2 个未解析元素的数量，因此下限取决于我们可以形成多少对，即下限 ((k - 1) / 2)。 由于该界限可以通过建设性重排来实现，因此对循环进行求和即可得出全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        
        visited = [False] * (n + 1)
        ans = 0

        for i in range(1, n + 1):
            if not visited[i]:
                cur = i
                cycle_len = 0
                while not visited[cur]:
                    visited[cur] = True
                    cycle_len += 1
                    cur = p[cur - 1]

                if cycle_len >= 3:
                    ans += (cycle_len - 1) // 2

        print(ans)

if __name__ == "__main__":
    solve()
```该代码首先使用标准排列遍历构建循环。 每个位置都被访问一次，确保线性复杂度。 从周期到答案的转换直接使用导出公式，避免了任何交换模拟。 

重要的实现细节是索引：排列在逻辑上是基于 1 的，但存储时是基于 0 的，因此每个转换都使用 p[cur - 1]。

 ## 边缘情况

 像 p[i] = i 这样的单元素循环没有任何贡献。 遍历立即标记其已访问并跳过贡献，符合固定点已经有效的要求。 

像 [2, 1] 这样的二元素循环已经是有效的相互对。 循环长度为 2，因此公式贡献为零，并且不执行交换。 

诸如 [2, 3, 4, 5, 1] 之类的长奇数循环产生的循环长度为 5。该算法贡献 2 次交换，这对应于每次交换重复修复两个放错位置的元素，直到仅保留有效结构。 

循环的不相交联合表明了独立性。 例如，[2, 1, 4, 3, 5] 分为大小为 2、2 和 1 的循环，所有贡献均为零，从而确认算法不会错误地混合组件。
