 ## 解决方案
 ## 问题理解

 我们给定一个整数数组，需要识别总和为零的子数组或连续段。 这些片段被称为美丽。 我们的任务不仅仅是找到所有美丽的片段，而是最大化它们的数量而不重叠。 换句话说，一旦一个段被算进去，它里面的任何元素都不能出现在另一个漂亮的段中。 

输入由多个测试用例组成，每个测试用例都有一个可能很大的数组。 数组长度可以达到 100,000，所有测试用例的长度总和限制为 300,000。 检查所有可能的子数组是否为零和的简单解决方案是不可行的，因为子数组的数量随数组长度呈二次方增长。 这排除了任何 O(n²) 方法。 我们需要一个算法，每个测试用例的运行时间大致为 O(n) 或 O(n log n)。 

不明显的边缘情况包括具有许多零的数组、仅整个数组和为零的数组以及具有可形成多个不重叠的零和段的重复模式的数组。 例如，`[0, 0, 0]`应该返回`3`因为每个零都可以是一个段，而仅尝试最大长度段的粗心方法可能会返回`1`。 

## 方法

 暴力方法将迭代所有可能的起始索引，并针对每个索引检查所有可能的结束索引以查看子数组之和是否为零。 该方法原则上是正确的，因为它探索了每个段，但每个数组需要 O(n²) 次操作。 当 n 达到 10^5 时，在最坏的情况下这将执行大约 10^10 次操作，远远超过任何合理的时间限制。 

解锁更快解决方案的关键观察是零和段对应于重复的前缀和。 如果我们计算数组的前缀和，那么一个段`[l, r]`总和为零，如果`prefix[r] - prefix[l-1] = 0`。 重新排列，这意味着`prefix[r] = prefix[l-1]`。 因此，每当我们看到以前见过的前缀和时，我们就可以在那里结束一个美丽的片段。 为了最大化非重叠段，每当我们检测到重复的前缀和时，我们都会贪婪地结束一个段，然后重置我们的跟踪以避免重叠段。 

这导致每个测试用例使用一组来跟踪自上一段以来看到的前缀和，从而获得最佳的 O(n) 解决方案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 前缀和+集合| O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 初始化变量`count`为零。 这将存储找到的美丽片段的数量。 
2. 初始化变量`prefix`为零以跟踪数组元素的运行总和。 
3.初始化一组`seen`包含零。 该集合存储自上一个段结束以来看到的前缀和。 
4. 迭代数组的每个元素。 将当前元素添加到`prefix`。 
5. 检查是否`prefix`已经在`seen`。 如果是，则增加`count`因为一段美好的片段到这里就结束了。 重置`seen`仅包含零并重置`prefix`到下一个段为零。 这确保了段不重叠。 
6. 如果`prefix`不在`seen`，将其添加到`seen`并继续。 
7. 处理完数组后，`count`包含最大数量的不重叠的美丽片段。 输出当前测试用例的该值。 

为什么它有效：集合`seen`确保我们跟踪自最后一个段结束以来所有可能的前缀和。 当我们第一次看到重复的前缀和时，我们已经找到了结束段的最早点，而不会错过潜在的后续段。 重置集合可以保证不重叠，并且贪婪方法可以最大化段的数量，因为我们总是尽早结束段。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        count = 0
        prefix = 0
        seen = set()
        seen.add(0)
        
        for x in a:
            prefix += x
            if prefix in seen:
                count += 1
                seen = set()
                seen.add(0)
                prefix = 0
            else:
                seen.add(prefix)
        
        print(count)

if __name__ == "__main__":
    solve()
```该代码将前缀和跟踪和可见前缀和集初始化为零。 当它迭代数组时，它会检查自上一个段以来是否已经看到当前的前缀和。 当它达到时，一个段结束，该组被重置，并且继续计数。 使用集合可以避免重复扫描重复项，并确保每个元素的检查时间为 O(1)。

 ## 边缘情况

 对于`[0, 0, 0]`，算法开始于`prefix = 0`和`seen = {0}`。 第一个零触发`prefix in seen`，将计数增加到 1 并重置`prefix`和`seen`。 随后的每个零都会重复此过程，总共产生三个段。 这证实了贪婪方法可以正确处理连续的零。 

为了`[3, -3, 3, -3]`，前缀和是`[3,0,3,0]`。 该算法检测索引 1 处的第一个零前缀和，对一个段进行计数，重置，然后在索引 3 处检测另一个零前缀和，对第二个段进行计数。 这与预期的最大 2 个不重叠段相匹配，证明了交替正数和负数的正确性。
