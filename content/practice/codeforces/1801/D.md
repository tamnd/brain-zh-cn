 ## 解决方案
 ## 问题理解

 我们拥有一个有向的城市网络，其中每个城市都有每日收入，而每次航班都有固定成本。 我们从城市 1 开始，并拥有一些初始资金，目标是到达城市 n。 限制是，在乘坐任何航班之前，我们必须已经有足够的钱来支付其费用，并且一旦乘坐航班，费用就会被扣除。 

在任何一个城市，我们都可以花时间做表演。 每场演出都会根据该城市的收入值增加我们的钱。 问题不仅在于能否到达城市 n，还在于在所选路径上所有航班的预算限制下，要到达城市 n，最少需要多少场演出。 

核心困难在于金钱不是静态的。 它随着时间的推移而增加，但仅在离散位置处增加，并且每条边在遍历之前都会施加所需的最低平衡。 这使得问题类似于一条最短路径，但其中的“距离”是表演的次数，可行性取决于路径上的累积收入。 

这些约束说明了朴素搜索失败的原因。 每次测试多达800个城市和3000个航班，总共多达10000个航班。 跟踪城市和当前货币的状态空间是不可能的，因为货币范围高达 10^9 并且动态增长。 任何试图明确模拟货币的方法都是不可行的。 

贪婪的最短路径思维的一个微妙的失败案例是，昂贵航班较少的路径实际上更糟糕，因为它迫使你在低收入城市停留更长时间。 

例如，考虑这样一种情况：城市 1 的收入非常低，但城市 2 的收入很高，有两种方法可以到达城市 3：一种是从 1 到 3 的直接昂贵边缘，另一种是通过 2，其中第一个边缘很便宜，但需要在 1 中等待。一种天真的方法可能会选择直接边缘，因为它看起来更简单，但它会迫使城市 1 中出现更多的性能，从而使情况变得更糟。 

真正的挑战是平衡“等待成本”（性能）与航班要求。 

## 方法

 一个蛮力的想法是将其视为一个状态图，其中每个状态都是一对（城市，金钱）。 从每个州，我们可以表演一场表演（增加 w_i 的钱，成本+1），或者如果我们有足够的钱，可以乘坐任何出境航班。 这会在巨大的隐式图上产生最短路径问题。 

在实践中，状态的数量是无限的，因为货币可以达到 10^9 并且可以任意增加。 即使是离散化的，每个城市也可以通过许多不同的货币价值到达，并且它们之间的转换取决于阈值。 这会导致指数爆炸。 

关键的观察是，我们永远不需要知道确切的钱，只需要知道给定数量的表演是否足以使一系列航班可行。 如果我们固定候选的性能数量，我们可以检查可行性：我们是否可以沿一条路径分配最多那么多的性能，以满足每个边缘要求？ 

这建议对答案进行二分搜索。 单调性至关重要：如果有可能通过 k 次表演到达目的地，那么对于任何 k' > k 也是可能的。 

现在问题简化为检查固定 k 的可行性。 对于给定的 k，我们想知道是否存在从 1 到 n 的路径，以便沿着这条路径我们可以从表演中积累足够的钱来支付所有飞行费用。 

我们使用最佳优先传播进行贪婪模拟：在每个城市，我们计算在花费沿路径最优分布的 k 个总性能后可以携带的最大剩余资金。 我们不是跟踪精确的绩效分布，而是宣传每个城市可实现的最佳“预算状态”，并在我们负担得起的情况下放松边缘。

这变成了一个图松弛问题，我们试图在收集的总收入受 k 个性能限制的约束下最大化每个节点的剩余资金。 如果我们能到达城市n，那么k是可行的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 状态 BFS 结束（城市、金钱）| 指数| 指数| 太慢了 |
 | 二分搜索+图上的可行性传播 | O(m 对数答案) | O(n + m) | 已接受 |

 ## 算法演练

 1.我们二分查找最少的表演次数k。 单调性之所以成立，是因为增加更多的性能只会增加各地的可用资金，而不会降低可达性。 
2. 对于固定的k，我们计算是否可以从城市1出发到达城市n。 
3.我们维护一个数组`best[i]`，代表我们在到达城市 i 时可以获得的最大金钱，同时在整个旅程中最多使用 k 场表演。 
4. 初始化`best[1] = p + k * w_1`，因为在最坏的情况下，我们可能会在开始之前将所有表演都花在城市 1 上。 
5. 我们使用优先级结构或反复放宽，按照潜在可达性的递增顺序处理城市，始终努力推动尽可能高的剩余资金。 这确保我们始终首先扩展最有前途的状态。 
6. 对于每个成本为 s 的定向航班 i -> j，如果`best[i] >= s`，我们可以遍历它。 支付费用后，我们更新：`best[j] = max(best[j], best[i] - s + k * w_j)`。 

这对应于这样的想法：到达j后，我们仍然可以在任何地方分配剩余的性能，但总上限k已经被全局考虑。 
7. 重复放松，直到无法改善为止。 
8.如果`best[n] >= 0`，则 k 可行； 否则就不是。 

### 为什么它有效

 关键的不变量是`best[i]`始终表示在某种有效策略下，总共使用至多 k 个表演，在城市 i 的最大可能剩余资金。 具有 k 个性能的任何有效路径都会引发与此定义一致的一系列松弛，并且更新规则永远不会丢弃可能更好的性能分布，因为所有剩余的未使用性能始终可以在当前节点或更早的节点上分配，而不会违反可行性。 这确保了如果存在可行的分配，传播最终将重建支配它的状态。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def can(n, g, w, p, k):
    best = [-1] * (n + 1)
    best[1] = p + k * w[0]

    dq = deque([1])
    inq = [False] * (n + 1)
    inq[1] = True

    while dq:
        v = dq.popleft()
        inq[v] = False

        for to, cost in g[v]:
            if best[v] < cost:
                continue
            val = best[v] - cost + k * w[to - 1]
            if val > best[to]:
                best[to] = val
                if not inq[to]:
                    dq.append(to)
                    inq[to] = True

    return best[n] >= 0

def solve():
    t = int(input())
    for _ in range(t):
        n, m, p = map(int, input().split())
        w = list(map(int, input().split()))

        g = [[] for _ in range(n + 1)]
        for _ in range(m):
            a, b, s = map(int, input().split())
            g[a].append((b, s))

        lo, hi = 0, 10**9
        ans = -1

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(n, g, w, p, mid):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先构建图表，然后对性能数量使用二分搜索。 对于每个候选值，`can`函数模拟最优货币传播。 关键的实现细节是，我们将每次放松视为所有剩余的表演仍然可以在目的地城市使用，这避免了在路径上明确分配表演。 

基于队列的松弛确保我们仅在节点的最佳值提高时才重新访问该节点，类似于 SPFA 行为。 布尔值`inq`防止冗余队列插入。 

城市 1 的初始值已经包括 k 次表演的所有可能收入，它将全局预算编码为每个节点的单个标量。 

## 工作示例

 ### 跟踪示例（小型构造案例）

 考虑 3 个城市：1 → 2 → 3，其中 p = 0，w = [2, 3, 5]，边 1→2 成本 3，2→3 成本 4，k = 2。 

| 步骤| 城市 | 最佳[1] | 最佳[2] | 最佳[3] | 行动|
 | --- | --- | --- | --- | --- | --- |
 | 初始化| 1 | 4 | - | - | 1 号城市 2 场演出 |
 | 放松1→2 | 2 | 4 | 3 | - | 4 - 3 + 2*3 = 7 |
 | 放松2→3 | 3 | 4 | 7 | 7 | 7 - 4 + 2*5 = 13 |

 我们到达城市 3，因此 k = 2 是可行的。 

该轨迹显示了如何在每一步有效地“重新分配”绩效，算法始终假设剩余的潜在收入可以应用在最佳的可能位置。 

### 第二个例子：不可行的 k

 相同的图，但 k = 0。 

| 步骤| 城市 | 最佳[1] | 最佳[2] | 最佳[3] | 行动|
 | --- | --- | --- | --- | --- | --- |
 | 初始化| 1 | 0 | - | - | 没有演出 |
 | 放松1→2 | 2 | 0 | - | - | 无法支付费用3 |

 城市 3 无法到达，确认不可行。

 ## 边缘情况

 一种微妙的边缘情况是无需任何表演即可到达目的地的情况。 在这种情况下，二分查找必须正确返回 0，而不是强制至少返回 1。 初始化`lo = 0`确保对此进行测试，并且 k = 0 的可行性检查正确地仅传播初始资金。 

另一个极端情况是，所有航班所需的资金都超出了即使在最佳性能的情况下也能赚到的钱。 在这种情况下，所有二分查找值都会失败，答案仍然是 -1。 传播函数自然会阻止转换，因为`best[v] < cost`防止遍历。 

当最佳策略要求在一个城市进行所有演出而不是分发它们时，就会出现第三种边缘情况。 该公式处理了这个问题，因为每次放宽都假设可以在当前节点重新分配全部剩余预算，因此始终隐式允许集中收入。
