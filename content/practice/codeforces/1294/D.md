 ## 解决方案

 ## 问题理解

 我们正在构建一个数组，一次一个元素。 每次插入后，我们可以使用特殊操作“重新配置”值：我们可以添加或减去固定数字$x$任何元素，只要我们不低于零，就可以任意多次。 执行任何此类调整后，我们想知道阵列的最大可能 MEX。 

关键是数组元素不再是固定值。 每个号码$y$我们插入的不仅仅是一个值，而是可能值的整个算术级数：$$y, y + x, y + 2x, \dots$$并且也向下移动$x$只要我们保持非负数，这意味着可以从$y$所有数字都完全等于$y \bmod x$，但仅限于非负整数。 

所以每次查询后，我们想知道：前缀有多大$[0, 1, 2, \dots]$我们可以使用可用的数字来完全“覆盖”，其中每个数字在其残差类模中贡献一个槽$x$。 

约束条件达到$4 \cdot 10^5$，所以任何解必须接近线性或$O(n \log n)$。 任何尝试模拟操作或维护每个元素的完整可达值集的操作都会失败，因为每个查询可能会触发整个数组的大规模重新计算。 

一个经常破坏解决方案的天真的误解是独立对待每个元素，并认为我们可以自由地将值转换为任何非负整数。 这是错误的：我们受到模数的限制$x$。 例如，如果$x = 3$，像 1 这样的值只能变成$1, 4, 7, 10, \dots$，绝不是 2 或 3。 

当多个元素竞争相同的残基类别时，会出现微妙的失败情况。 例如，如果许多数字与 0 mod 全等$x$，它们都“生活”在同一个桶中，并且不能独立用于所有所需的小整数。 

## 方法

 一个强力的想法是在每次查询后维护完整的数组，并且对于每个候选 MEX 值$m$，检查是否可以使用模约束下的可用元素来形成它。 这将涉及模拟将数字分配给目标$0, 1, 2, \dots$，反复检查每个查询的可行性。 在最坏的情况下，这会变成$O(n^2)$或者更糟糕的是，因为每个查询可能需要扫描许多值并可能需要调整许多元素。 

关键的结构见解是每个数字仅通过其余数模数起作用$x$，因为允许的操作保留了该残差类。 所以每个元素都属于其中一个$x$独立桶。 

现在考虑构建 MEX$0$向上。 形成一个数字$m$，桶中必须至少有一个未使用的元素$m \bmod x$。 每个元素只能使用一次，因此每个存储桶的行为就像一个可用“槽”队列，用于容纳剩余的数字。 当我们分配数字时$0, 1, 2, \dots$，我们从每个相应的残差桶中消耗一个元素。 

因此，问题简化为维护每个剩余类被看到的次数，并贪婪地检查最小的缺失 MEX。 

挑战是在查询到达时动态维护这一点。 我们为每个残差类维护一个指针，指示该类中有多少元素已用于形成早期的 MEX 值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n^2)$|$O(n)$| 太慢了 |
 | 最佳 |$O(n)$|$O(x)$| 已接受 |

 ## 算法演练

 我们维护两个主要结构：每个残基类模的频率计数器$x$，以及跟踪最小 MEX 候选的全局指针。 

各残基类别$r$存储有多少个元素$y \equiv r \pmod{x}$已插入。 

1. 对于每个传入的值$y$, 计算$r = y \bmod x$，并增加桶的数量$r$。 这反映了在该残基类中添加了一个更多可用的元素。 
2. 维护当前的MEX指针$mex$，从 0 开始。这代表我们尚未确认可构造的最小值。 
3、每次插入后，反复检查当前是否存在$mex$可以形成：

 这需要那个桶$mex \bmod x$其元素数量严格多于我们已经使用该残差类作为早期 MEX 值的次数。 
4. 如果可能，我们“消耗”该残基类中的一个元素并递增$mex$。 该模型分配以前未使用的元素来表示此 MEX 值。 
5. 下一个时停止$mex$由于残渣桶中元素不足而无法成型。 输出电流$mex$。 

我们只搬家的原因$mex$向前的意思是，一旦一个数字在给定时刻被确认为不可能，当更多元素到达时，它可能会在稍后变得可能，但以前的值永远不会被重新访问。 

### 为什么它有效

 不变量是，在任何时间，对于每个值$v < mex$，我们已经将其与残基类允许的不同元素进行了匹配。 对于每一个这样的$v$，我们只使用了存储桶中的一个元素$v \bmod x$。 

当我们试图扩展到$mex$，我们正在检查所需的残差类中是否存在未使用的元素。 如果是，我们将其永久分配给$mex$。 如果不是，则将来对早期元素的重新分配将无法在不破坏先前分配的情况下有所帮助，因为这些元素已被提交。 这使得贪婪分配最优并确保$mex$总是最大化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q, x = map(int, input().split())
    cnt = [0] * x
    
    mex = 0
    
    for _ in range(q):
        y = int(input())
        r = y % x
        cnt[r] += 1
        
        # try to extend mex greedily
        while cnt[mex % x] > mex // x:
            mex += 1
        
        print(mex)

if __name__ == "__main__":
    solve()
```该解决方案仅维护残留计数和单个递增指针。 条件`cnt[mex % x] > mex // x`准确捕获该残基类中是否有足够的元素可以分配给当前的 MEX 位置。 

该部门`mex // x`表示在构建 MEX 序列的早期部分时，该残基类别中的先前数字数量已被消耗。 

循环仅向前推进，因此总运动`mex`所有查询都是线性的。

 ## 边缘情况

 关键的边缘情况是所有查询中仅出现一个残基类别。 在这种情况下，只有与该类模一致的数字$x$可以形成，因此 MEX 立即停止在 0。 该算法处理这个问题是因为`cnt[mex % x]`永远不会超过零，当`mex % x`是缺少的类。 

另一种情况是当$x = 1$。 那么每个数字都属于同一个残基类别，每次插入都会直接增加可用池。 该条件简化为纯粹的计数比较，并且 MEX 等于已处理元素的数量，这是算法自然产生的，因为`cnt[0]`总是成长并且`mex`一步步前进。
