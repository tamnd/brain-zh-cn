 ## 解决方案

 ## 问题理解

 机器人从网格的原点开始，只能向两个方向移动：向右或向上。 每个包都位于具有非负整数值的不同网格坐标处。 机器人必须从原点出发访问所有包裹位置，并且可以自由选择访问顺序。 每次移动都会使 x 坐标或 y 坐标加一。 

任务是确定是否存在访问所有点的顺序，以便机器人永远不需要向左或向下移动，同时仍然能够按该顺序到达每个包裹。 如果存在这样的顺序，我们必须构造一个有效的最短路径字符串。 在所有最短的有效路径中，我们必须输出字典顺序最小的路径，其中“R”被认为小于“U”。 

这些约束使解决方案与线性或近线性排序逻辑紧密结合。 所有测试用例的总点数最多为 1000，因此 O(n log n) 排序策略就足够了。 任何涉及所有订单的排列或回溯的事情都会发生组合爆炸，并且在超过非常小的 n 后立即不可行。 

当点在单调遍历方面“不兼容”时，就会出现一个微妙的问题。 例如，如果我们有点 (1, 2) 和 (2, 1)，则没有单调路径可以在不违反单调性的情况下以 x 和 y 移动的单个递增序列访问这两个点。 任何强制命令的尝试最终都需要向下或向左移动，这是不允许的。 

一个幼稚的错误是尝试仅按 x 或仅按 y 对点进行排序。 例如，仅按 x 排序可能会产生一个序列，其中 y 在连续点之间递减，从而使得直接单调遍历变得不可能。 类似地，点的任意排序会导致机器人需要“返回”的无效中间状态。 

## 方法

 一个蛮力的想法是尝试点的所有排列，检查是否只能使用向右和向上的移动来遍历每个排序，并跟踪有效路径中字典顺序最小的最佳路径。 对于每个排列，我们模拟从 (0,0) 到第一个点，然后在连续点之间移动，验证两个坐标永远不会减少。 这是有效的，因为它明确地强制执行可行性，但它需要检查 n! 阶，即使 n = 10，这在计算上也已经变得不可行。 

关键的结构观察是任何有效路径都必须以非递减 x 和非递减 y 方式移动。 这意味着一旦我们承诺访问具有较大 x 的点，我们以后就永远无法访问具有较小 x 的点。 这同样适用于连续点之间的相对排序约束中的 y。 

这表明，如果我们按 x 坐标对点进行排序并按升序处理它们，我们会自动保证永远不需要向左移动。 唯一剩下的问题是在相等的 x 值内我们是否可以保持可行性。 对于字典顺序最小的输出，我们希望尽可能早地产生“R”，这与在 y 转换之前优先考虑较小的 x 转换相一致。 

然而，关键的改进是我们实际上不需要在点本身之间强制执行严格的排序。 相反，我们只关心从当前位置移动到下一个目标时，我们只能向右和向上移动，这意味着两个坐标必须沿着所选序列不递减。 因此，最佳策略是按 x 升序对点进行排序，对于相等的 x，按 y 升序对点进行排序。 这确保了两个维度上的单调递增链，从而保证了可行性。

一旦这条链被固定，构建路径就很简单：从当前位置向右移动直到到达下一个 x，然后向上移动直到到达下一个 y。 因为 x 永远不会减少，y 也永远不会减少，所以这总是有效的。 

字典顺序最小的要求自然得到满足，因为我们总是在可能的情况下在每个阶段的“U”移动之前用尽所有所需的“R”移动。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n!) | O(n) | 太慢了 |
 | 按坐标排序 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们通过排序点强制单调进行来构建有效路径。 

1. 读取测试用例的所有包坐标。 这些代表机器人必须到达的目标单元。 
2. 通过增加 x 坐标对所有点进行排序，对于相等的 x，通过增加 y 坐标对所有点进行排序。 这确保了在列表中移动时，两个坐标都不会减少，因此不需要向后移动。 
3. 将当前位置初始化为 (0, 0) 并返回一个空结果字符串。 
4. 迭代排序的点。 对于每个点 (x, y)，使用“R”步长从当前 x 水平移动到 x，然后使用“U”步长从当前 y 垂直移动到 y。 将这些动作附加到答案字符串中。 这种排序是强制的，因为首先向右移动可以保留词典编排的最小性。 
5.处理完所有点后，输出构造的路径。 

为什么它有效

 排序顺序保证 x 和 y 沿着访问点的序列不递减。 这确保了仅使用向右和向上移动即可实现连续点之间的每次转换。 由于我们总是在垂直移动之前完成所有水平移动，因此我们在所有有效的单调路径中按字典顺序生成尽可能小的字符串，因为任何较早插入“U”的尝试都会延迟必要的“R”并产生字典顺序更大的前缀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]
    
    pts.sort()
    
    x, y = 0, 0
    res = []
    ok = True
    
    for nx, ny in pts:
        if nx < x or ny < y:
            ok = False
            break
        
        res.append('R' * (nx - x))
        res.append('U' * (ny - y))
        x, y = nx, ny
    
    if not ok:
        print("NO")
    else:
        print("YES")
        print(''.join(res))
```该代码首先按字典顺序对点进行排序，这对应于先按 x 排序，然后按 y 排序。 这保证了可行性检查所需的单调性。 我们维护机器人当前位置的指针，并通过精确添加到达每个连续点所需的向右和向上移动的次数来增量构建路径。 

有效性检查确保我们永远不会试图倒退。 如果任何点相对于前一个点违反了单调性，则构造失败。 

构造顺序至关重要：我们总是在“U”移动之前附加所有必需的“R”移动，这确保了有效单调路径中字典顺序的最小性。 

## 工作示例

 ### 示例 1

 输入点：(1,3)、(1,2)、(3,3)

 排序后得到：(1,2),(1,3),(3,3)

 | 步骤| 当前 (x,y) | 目标 (x,y) | R 移动 | U移动| 路径|
 | ---| ---| ---| ---| ---| ---|
 | 1 | (0,0) | (0,0) | (1,2) | 右 | 呃| RUU |
 | 2 | (1,2) | (1,3) | | 你| 鲁乌 |
 | 3 | (1,3) | (3,3) | RR | | 鲁乌鲁 |

 该跟踪表明排序将看似“未排序”的输入解析为单调链。 机器人永远不需要减少坐标，证实了可行性。 

### 示例 2

 输入点：(1,0)、(0,1)

 排序后：(0,1),(1,0)

 | 步骤| 当前| 目标| 有效过渡 |
 | ---| ---| ---| ---|
 | 1 | (0,0) | (0,0) | (0,1)| 你|
 | 2 | (0,1)| (1,0)| 无效（y 减小）|

 这会立即失败，因为 y 需要从 1 减少到 0。算法正确地输出 NO。 

这表明仅排序是不够的，除非单调可行性成立（检查强制执行）。

 ## 边缘情况

 (0,0) 处的单个包被干净地处理，因为不需要移动并且排序的序列仍然有效。 输出只是“是”，路径为空，符合机器人已位于该位置的要求。 

需要沿相反对角线方向交叉的两个点（例如 (1,0) 和 (0,1)）会立即失败，因为排序会产生需要减小坐标的步骤。 该检查在任何路径构建之前捕获这一点，确保正确性。 

所有点都位于一条递增线上的情况，例如 (0,0)、(1,0)、(2,0)，表明该算法退化为纯粹的“R”移动序列，没有不必要的复杂性，从而确认了构造的最优性。
