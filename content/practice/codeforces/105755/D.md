 ## 解决方案
 ## 问题理解

 我们看到一排机器人，从左到右标记。 机器人$i$从位置开始$x = i$，所有机器人在零时刻开始向左移动。 简单来说，随着时间的推移，运动并不均匀，因为每次“慢动作射击”发射时，所有仍在直线正侧的机器人的速度都会减半。 这些射击只能在大于零的整数倍时发射，并且在任何这样的时间我们都可以发射多次射击，这相当于增加每个活动机器人在该确切时间被击中的次数。 

每个机器人都有规定的命中次数。 机器人$i$必须准确击中$a_i$次，其中序列$a_1 \le a_2 \le \dots \le a_n$是非减的。 该过程恰好在之后结束$a_n$已经发射了总枪数，并且如果不同的时间表在任意整数时间发射的枪数不同，则被认为是不同的。 

任务是计算存在多少个有效的触发计划，以 998244353 为模。 

约束条件$n \le 100$和$a_i \le 100$告诉我们，机器人的数量和最大射击“层”数都很小。 这强烈表明在值范围内进行动态规划或组合构造$a_i$，而不是任何取决于实际连续运动模拟的东西。 运动细节的存在是为了定义约束，但解决方案最终必须减少到计算跨整数时间步分布事件的结构化方法。 

一个关键的微妙之处在于，对物理学的天真的解释是具有误导性的。 机器人的精确连续位置与盘点时间表无关。 重要的是每个机器人何时不再受到未来射击的影响，这仅取决于它已经被击中的次数，而不是确切的时间。 

一个常见的失败案例是在每次速度变化后尝试模拟运动或跟踪精确位置。 例如，尝试在重复减半的情况下计算每个机器人的精确碰撞时间会导致浮动行为，并且不符合有效射击计划的组合结构。 

## 方法

 蛮力视角将问题视为选择，对于每个整数时间$t = 1, 2, \dots, a_n$，要开多少枪。 由于镜头总数是固定的，这成为一个分区问题$a_n$时间段。 然而，并不是每个分区都是有效的，因为每个机器人都会施加约束：一旦机器人被击中$a_i$次，以后就不能再受影响了。 这将跨机器人和时间的决策以及所有分布的简单枚举结合起来$a_n$时间上的镜头是指数级的$a_n$，即使对于$a_n = 100$。 

关键的观察是单调性$a_i$意味着分层结构。 目前，当我们考虑$k$第一个镜头，正是机器人$a_i \ge k$仍然“活跃”，因为它们仍然需要未来的点击。 自从$a_i$是非减的，这些活跃集形成了机器人的前缀。 这将问题转化为为每个射击级别构建一个时隙序列，其中每个级别都有一个由仍需要该级别的最后一个机器人确定的上限。 

我们不再对运动进行推理，而是将过程重新解释为调度$a_n$事件按“重要性级别”升序排列，其中级别$k$必须在机器人的某个截止指数停止允许在该级别进行进一步射击之前发生。 这将几何图形折叠成嵌套约束上的纯粹组合计数问题。

 | 前缀约束上的分层DP$O(n \cdot a_n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们逐级处理问题，其中level$k$对应于$k$整个系统的第 次射击。 

1. 每个级别$k$，确定哪些机器人在该级别仍然“相关”。 一个机器人$i$与级别相关$k$如果至少还需要$k$命中，意义$a_i \ge k$。 因为$a_i$排序后，这些机器人形成一个前缀$1 \dots p_k$， 在哪里$p_k$是最大的索引$a_{p_k} \ge k$。 
2. 解释级别$k$就像选择时间一样$t_k$为$k$第-个射击活动单位。 唯一的限制是$t_k$重要的是，它必须发生在所有在此级别不再相关的机器人将使未来的镜头“无效”之前。 这转化为由下式确定的上限$p_k$。 
3. 一旦我们修复$p_k$，有效整数选择的数量$t_k$正是$p_k - (k - 1)$。 出现减法是因为序列$t_1 < t_2 < \dots$必须严格递增，所以$k$-第一个选择必须放在前一个选择之后$k-1$时间点。 
4. 增加各个级别的选择数量$k = 1 \dots a_n$，因为一旦前缀边界固定，不同级别的选择是独立的。 
5. 返回对 998244353 求模后的乘积。 

计算减少到扫描级别$1$到$a_n$，维护最右边的索引$p_k$对于每个级别，使用向左移动的指针$k$增加。 

### 为什么它有效

 核心不变量是在水平上$k$，唯一重要的限制是哪些机器人仍然需要至少$k$命中。 这些机器人对允许的放置位置施加上限。$k$-th 发射时间，而机器人需要的时间少于$k$点击率已经与未来的决策“脱钩”。 因为相关机器人的集合单调收缩$k$，约束随着时间索引形成嵌套间隔。 这种嵌套确保每个级别贡献一个独立的乘法因子，该乘法因子等于考虑了早期放置后剩余的有效整数槽的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    a.sort()
    max_k = a[-1]
    
    # p[k] = largest index i such that a[i] >= k
    p = [0] * (max_k + 1)
    
    j = n - 1
    for k in range(1, max_k + 1):
        while j >= 0 and a[j] >= k:
            j -= 1
        p[k] = n - 1 - j
    
    ans = 1
    for k in range(1, max_k + 1):
        choices = p[k] - (k - 1)
        ans = (ans * choices) % MOD
    
    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先对需求数组进行排序，以便前缀结构变得明确。 对于每个级别$k$，我们计算至少还需要多少个机器人$k$命中； 这存储在$p[k]$。 指针$j$只向左移动，确保$O(n + a_n)$预处理步骤。 

然后，每个级别贡献一个乘法因子，该因子等于该级别的有效位置数$k$- 考虑到之前已放置的时间后的第 次触发时间。 最终产品汇总了这些独立的选择。 

一个微妙的实施细节是确保$p[k]$被解释为计数，而不是索引，并且减法$(k-1)$正确地解释了时间点的严格递增结构。 

## 工作示例

 考虑样本$a = [1, 2, 5, 6, 8, 8]$。 

我们计算$p_k$以及一层一层的选择。 

| k | p_k | 选择= p_k - (k-1) |
 | ---| ---| ---|
 | 1 | 6 | 6 |
 | 2 | 5 | 4 |
 | 3 | 4 | 2 |
 | 4 | 4 | 1 |
 | 5 | 4 | 0 |

 一旦关卡没有有效的放置，乘积就会变为零，这反映出后来的约束迫使时间表过于紧张。 这与以下事实相符：由于小型和大型机器人的重叠要求，某些配置是不可能的。$a_i$。 

现在考虑一个统一的情况$a = [100, 100, 100, 100, 100]$。 每个级别都有$p_k = 5$，所以每个级别都有贡献$5 - (k-1)$。 这会产生严格递减的可用槽序列，对应于将所有镜头放置在严格约束的递增时间表中。

 ## 边缘情况

 一个最小的案例$n = 1$和$a_1 = 1$由于只有一个触发时间并且机器人之间没有交互，因此只能生成一个有效的时间表。 该算法计算$p_1 = 1$，给出单一选择。 

在这样的情况下$a = [1,1,1,1]$，每个级别只有一个活动机器人，因此每一步只贡献一个位置。 该算法维持$p_k = n$为所有人$k = 1$，并且产品始终保持 1。 

什么时候$a_n$很大，但许多早期的机器人都很小$a_i$，前缀大小迅速缩小$k$增加。 该算法通过单调指针捕获这一点，并且一旦$p_k < k$，产品正确变为零，因为无法形成有效的严格递增时间表。
