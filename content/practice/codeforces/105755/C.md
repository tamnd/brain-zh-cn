 ## 解决方案
 ## 问题理解

 给定一个正整数的多重集，我们想要选择一个没有重复项的子集，以便每对选定的数字都满足涉及 XOR 的严格按位条件。 

对于任意两个选定的数字$x$和$y$，我们计算$x \oplus y$。 要求是这个异或结果必须严格大于两个数字中较大的一个。 如果即使对于一对失败，则该子集无效。 

因此，任务是最大化我们可以选择的不同值的数量，同时保持子集中每一对的成对约束。 

约束条件$n \le 3 \cdot 10^5$立即排除任何显式检查所有对的方法。 在最坏的情况下，对所有子集的天真检查或什至使用成对比较的贪婪验证将是二次的，并且不会通过。 任何有效的解决方案都必须将元素之间的相互作用减少到更接近线性或线性时间。 

当许多数字共享相同的幅度范围时，就会出现关键的边缘情况。 例如，考虑一组数字，例如$4, 5, 6, 7$。 它们都位于相同的二次方区间，但它们的成对异或行为受到高度限制。 另一种边缘情况是当值分布在不同的幅度范围时，例如$1, 2, 3$，其中一些对表现良好，而另一些则立即违反条件。 一种仅比较相邻值或仅检查一个排序方向的天真的贪婪方法在这种混合情况下将失败。 

## 方法

 蛮力的想法很简单。 我们尝试每个子集并验证所有对是否满足 XOR 条件。 即使我们修复了一个子集并在中验证它$O(k^2)$，子集的数量是指数级的，所以这是完全不可行的。 

稍微更合理的尝试是对数组进行排序并尝试贪婪地构建子集，根据所有已选择的元素检查每个新候选者。 这减少了子集搜索，但验证步骤仍然变为$O(n^2)$在最坏的情况下，因为每次插入都可能扫描整个选定的集合。 

关键的观察结果来自于理解 XOR 相对于数字最高有效位的行为方式。 数字的值由其最高设置位决定。 当两个数字的最高设置位不同时，XOR 的行为方式往往会以非常结构化的方式破坏或保留大小。 

如果两个数字位于不同的最高位组，则其中之一具有严格更高的最高有效位。 在这种情况下，较大的数字在比较中占主导地位，并且 XOR 无法可靠地超过它，因为 XOR 永远不会引入高于任一操作数最高位的位。 这立即限制了哪些组合是候选组合。 

在固定的最高位组内，所有数字共享相同的前导位。 XOR 取消该位，这迫使结果低于该组的整个范围。 由于组中的每个数字至少$2^k$，而 XOR 保持低于$2^k$，同一组内的任何对都会自动违反该条件。 

这导致了结构的极大简化：每个最高位组中最多只能选择一个数字。 一旦认识到这一点，问题就简化为计算输入中表示了多少个不同的最高位组。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 太慢了 |

 ## 算法演练

 1. 对于每个数字，确定其最高有效位的位置。 这标识了该数字所属的二次方区间。 
2. 维护一个按位位置索引的布尔数组或集合，以跟踪哪些组已在所选子集中表示。 
3. 迭代所有数字。 对于每个数字，计算其 MSB 索引。 
4. 如果之前没有见过该 MSB 索引，则将其标记为已使用并递增答案。 否则，请跳过该数字，因为从同一组中选择多个元素将立即违反条件。 
5. 输出遇到的不同MSB组的总数。 

### 为什么它有效

 不变的是任何有效子集每个最高位类别最多可以包含一个元素。 在一个类中，每个数字都位于$[2^k, 2^{k+1})$。 对于任何两个这样的数字，XOR 会删除前导位并产生一个严格低于$2^k$，它总是小于两个原始数字。 这直接违反了 XOR 必须超过该对最大值的要求。 在不同的类中，选择多个元素通常也是不安全的，但类内部的约束已经迫使最优策略为每个类最多选择一个代表，并且任何有效子集都不能超过此界限。 因此，计算不同的 MSB 值可以得出最大可能的大小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def msb(x):
    return x.bit_length() - 1

n = int(input())
arr = list(map(int, input().split()))

seen = set()
ans = 0

for x in arr:
    b = msb(x)
    if b not in seen:
        seen.add(b)
        ans += 1

print(ans)
```该解决方案使用以下方法计算每个数字的最高有效位`bit_length`，每个整数以恒定时间运行。 套装`seen`确保我们只对每个位组计数一次。 

一个微妙的点是重复根本不重要，因为该问题需要一组唯一的元素。 即使输入中存在重复项，它们也会折叠到同一 MSB 组，并在第一次出现后被忽略。

 ## 边缘情况

 具有单个数字的最小输入始终会产生答案 1，因为没有任何对违反条件。 

对于像这样的情况`4 5 6 7`，所有数字共享相同的最高有效位。 该算法将它们分配到同一组，仅保留第一次出现的情况，并忽略其余的。 这符合以下事实：该范围内的任何对都无法满足 XOR 条件。 

为了`1 2 3`，分组分为 MSB 0（表示 1）和 MSB 1（表示 2 和 3）。算法正确地对两个组进行计数，匹配最佳可实现子集`{1, 2}`或者`{1, 3}`但从来没有全部三个。
