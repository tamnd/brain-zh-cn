 ## 解决方案
 ## 问题理解

 我们得到了一系列的上课日和一系列新闻事件，其中每个事件在连续的几天内都处于活动状态。 每天，必须有几个学生出席，每个学生都有一个热情值，该值控制他们“准备”当前活动活动的数量。 

在课程日开始时，我们会查看时间间隔涵盖当天且在之前的课程中未呈现的所有事件。 拨打这个号码$x$。 当天到达的每个学生都会独立选择一组准确的$\min(x, e_i)$那些活跃的事件。 这些选择是对抗性的，因为我们必须假设可以选择该大小的任何有效子集。 

在所有学生都选择了他们的组合后，埃兹拉可以决定学生呈现的顺序。 当学生被处理时，他们必须展示他们准备好的一组中尚未在该课程中早期使用过的事件。 如果他们准备好的整套已经被消耗掉，他们就会失败。 

任务是确定我们是否可以为每个班级选择学生的顺序，以便无论学生如何选择允许的子集，都不会出现任何学生失败的情况。 

关键的困难是我们无法控制学生准备哪些活动。 我们只知道他们准备的套装的大小，而不知道其内容。 这会产生最坏情况的组合约束，而不是简单的分配问题。 

限制很大，测试中的事件和学生总数高达$2 \cdot 10^5$。 任何尝试显式模拟子集的所有选择或在完整二分图上执行匹配的解决方案都将太慢，因为即使每个类每个事件的线性工作也已经超出了限制。 

当班级的所有事件都活跃但学生的热情值较小时，就会出现微妙的边缘情况。 即使事件总数足够，对抗性子集选择也可以将学生与彼此的可用选择隔离开来。 当事件跨越非常短的时间间隔时，会出现另一种边缘情况，导致可用资源快速变化。$x$，这会逐级影响可行性。 

## 方法

 蛮力观点独立对待每个类别。 我们想象显式地构建学生选择的子集，然后尝试贪婪地或通过二分匹配来分配事件。 这在概念上是正确的，因为一旦子集被固定，问题就减少到将学生与他们选择的集合中的不同事件相匹配。 

然而，这在计算上立即崩溃了。 每个学生可以选择大小的子集，最多可达$x$，并且这样的选择数量呈指数级增长。 即使我们修复单个对抗配置，解决每个类的匹配成本至少$O(k_i \cdot x)$或者$O(x^2)$在典型的实现中，这在限制下是不可能的。 

关键的观察是我们实际上不需要推理精确的子集。 我们只需要了解最坏情况的子集结构可以强制什么。 由于学生仅受他们选择的元素数量的限制，因此对手总是可以将他们选择的元素放置在相对于其他学生最不方便的位置。 这意味着我们唯一可以依赖的可靠信息是每个学生选择的集合的大小。 

这将问题转化为调度可行性条件。 每个学生实际上都有一个“类似于截止日期”的约束：如果他们按顺序处理得太晚，他们可能选择的所有事件可能已经被其他人消耗掉了。 这会将类转换为贪婪排序问题，并具有从这些集合大小派生的约束。 

一旦重新表述，每个类就变成了对源自以下的整数序列的条件检查问题$\min(e_i, x)$，解决方案简化为验证是否存在有效的排序。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每个子集的强力匹配 | 指数 /$O(x^2)$每堂课 |$O(x)$| 太慢了|
 | 减少安排可行性检查|$O(m \log m)$总计 |$O(m)$| 已接受 |

 ## 算法演练

 我们独立处理每个班级。 唯一的全局交互是计算每天有多少活动事件，因为每个事件仅在其正在进行且未使用时才对池做出贡献。 

### 1. 计算每天的活动事件

 我们在事件起点和终点上使用扫描线。 对于每一天$i$，我们维持$x$，当前处于活动状态且尚未在早期类中使用的事件数。 

在我们分配任何学生之前，该值对于班级来说是固定的，因此它定义了当天的选择范围。 

### 2. 通过可用的活动限制学生的能力

 以饱满的热情为每一位学生$e_i$，我们将其替换为$e'_i = \min(e_i, x)$。 这反映出学生无法准备比现有事件更多的独特事件。 

### 3. 将排序约束转换为位置条件

 我们会考虑班级内学生的任何有效顺序。 假设一个学生被安排在一个位置$p$（0-索引）。 那一刻，正是$p$事件已被消耗。 

仅当学生准备的所有事件都位于已使用的集合内时，学生才会失败。 由于对手可以选择大小的任何子集$e'_i$，如果使用的池足够大以完全包含大小的子集，则故障将不可避免$e'_i$。 

这导致在处理学生之前，剩余事件的数量必须满足$$x - p > x - e'_i$$这简化为$$p < e'_i.$$所以每个学生必须出现在第一个$e'_i$排序的位置。 

### 4. 检查作为截止日期调度问题的可行性

 我们现在有一个经典的约束：每项工作都有一个截止日期$e'_i$，并且我们必须将所有工作分配给职位$1..k_i$。 

全部排序$e'_i$按非递减顺序。 当且仅当对于每个位置，排序都是可行的$j$,$$e'_j \ge j.$$这个条件至少保证$j$学生可以被安排在第一$j$不违反最后期限的情况下的插槽。 

### 5. 对所有班级重复此操作

 如果每个类都独立地满足这个条件，那么我们就可以为每个类构造一个有效的排序。 

### 为什么它有效

 关键的不变量是任何对抗性子集选择仅通过集合大小而不是结构影响可行性。 因为对手总是可以将选定的子集嵌入到大小相同的共享池中$e'_i$，在最坏情况下的行为中幸存下来的唯一约束是要求学生足够早地得到处理，以便少于$e'_i$事件已被消耗。 

一旦这减少到截止日期限制，排序$e'_i$捕获尽可能严格的排序。 任何违反$e'_j \ge j$直接对应于一个前缀，其中必须过早安排太多低容量学生，从而强制保证失败配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def possible(e_list, x):
    # cap by available events
    e = [min(v, x) for v in e_list]
    e.sort()
    for i, v in enumerate(e, 1):
        if v < i:
            return False
    return True

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())

        classes = []
        total_k = 0
        for _ in range(n):
            tmp = list(map(int, input().split()))
            k = tmp[0]
            e = tmp[1:]
            classes.append(e)
            total_k += k

        events = []
        for _ in range(m):
            l, r = map(int, input().split())
            events.append((l, r))

        add = [[] for _ in range(n + 3)]
        rem = [[] for _ in range(n + 3)]

        for l, r in events:
            add[l].append(1)
            rem[r + 1].append(1)

        active = 0
        ptr = 0

        ok = True

        for day in range(1, n + 1):
            for _ in add[day]:
                active += 1
            for _ in rem[day]:
                active -= 1

            if not possible(classes[day - 1], active):
                ok = False
                break

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```该实现首先使用扫描事件边界来计算每天有多少活动事件。 对于每个班级，它会根据活动事件的数量限制每个学生的热情，并对结果值进行排序以验证调度条件。 

唯一微妙的一点是可行性检查仅取决于当前的情况$x$，不在任何事件身份结构上。 这就是为什么我们从不存储或分配实际事件； 只计算物质。 

## 工作示例

 ### 示例 1

 考虑一个具有活动事件的类$x = 3$和具有热情价值观的学生$[1, 2, 2]$。 

| 步骤| 已排序的 e' | 检查 |
 | ---| ---| ---|
 | 1 | [1,2,2]| 1 ≥ 1 好 |
 | 2 | [1,2,2]| 2 ≥ 2 好 |
 | 3 | [1,2,2]| 2 ≥ 3 失败 |

 第三个位置违反了条件，这意味着第三个学生将被迫陷入所有可能准备的事件都已被消耗的情况。 

这表明仅有足够的事件总数是不够的； 分配限制很重要。 

### 示例 2

 让$x = 3$和学生有$[3, 1, 1]$。 

| 步骤| 已排序的 e' | 检查 |
 | ---| ---| ---|
 | 1 | [1, 1, 3] | 1 ≥ 1 好 |
 | 2 | [1, 1, 3] | 1 ≥ 2 失败 |

 这里失败立即发生，因为两名学生需要位置 2 或更早的位置，但只有一名学生可以安全地放置在位置 1。 

这凸显出，在对抗性子集选择下，高能力的学生无法弥补多个低能力的学生。

 ## 边缘情况

 一个重要的情况是所有事件都涵盖所有日期。 然后$x$是常数且最大。 该算法简化为仅检查学生排序约束，任何失败纯粹来自于热情值的分布。 扫描线不会干扰正确性，因为活动计数保持稳定。 

另一种情况是当事件非常稀疏时，导致$x$对于大多数班级来说都很小。 在这种情况下，所有学生都会受到很大的限制，许多热情值会崩溃到相同的值。 基于排序的检查自然会处理这个问题，因为它统一处理所有上限值。 

最后一个微妙的情况是$x = 0$。 然后全部$e'_i = 0$，任何有学生的班级都会立即失败，因为第一个学生不能满足$e'_1 \ge 1$。 这与不存在可呈现的事件的现实相符，因此不可能进行任何呈现。
