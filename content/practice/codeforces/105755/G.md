 ## 解决方案
 ## 问题理解

 我们得到了一组小的二进制网格，每个网格的大小$m \times m$，其中每个单元格要么为空，要么已填充。 关键操作是一种“网格替换”的形式：当组合两个网格时$T_1$和$T_2$，每个填充的单元格$T_1$被完整副本取代$T_2$，而每个空单元格都被替换为$m \times m$空单元格块。 结果是尺寸更大的网格$m^2 \times m^2$。 

任务是计算在此操作下有多少对输入网格进行通勤，这意味着以任一顺序组合它们都会产生完全相同的结果大网格。 

尽管输入大小可能很大，最多可达$10^5$网格，每个网格都非常小$m \le 5$。 这立即表明，任何将每个网格视为一个小对象并对它们进行散列或比较的解决方案都是可行的，但任何尝试显式模拟组合的方法都是不可能的。 单个组合物的尺寸已经扩大$m^2 \times m^2$，并且对许多对执行此操作会导致计算量爆炸。 

很容易被忽视的主要边缘情况是，组合下的平等比看起来要严格得多。 例如，“看起来对称”的两个不同网格通常不会交换，因为替换操作取决于填充单元格的确切位置。 即使是单个填充的细胞也可以完全确定结构的复制方式。 

如果假设交换性可能适用于结构化模式（例如不同位置的完整网格或稀疏网格），则会出现微妙的失败情况。 例如，如果一个网格有一个填充单元，另一个网格有多个填充单元，则以不同的顺序组合它们会产生不同数量的复制块，因此相等性无法成立。 这排除了大多数“结构对称”猜测，并将解决方案推向识别操作下两个网格何时是实际上无法区分的对象。 

唯一能够承受所有结构约束的稳健等价性是网格的字面相等性。 

## 方法

 暴力方法将计算每对的组合网格$(T_i, T_j)$在两个订单中并比较结果。 每个组合物都扩展了一个$m \times m$网格成$m^2 \times m^2$网格，因此单个组合成本$O(m^4)$。 和$n^2$对，这变成$O(n^2 m^4)$，当$n = 10^5$。 

关键的简化是理解什么样的结构在组合中仍然存在。 该操作不会混合不同小区之间的信息； 它只复制整个块。 这使得结果完全由填充单元格的模式决定，并且这些模式中的任何不匹配都会在输出中乘法传播。 

一个重要的观察是，如果两个网格交换，那么以任何顺序组合它们都必须在每个级别产生相同的块结构。 这会强制执行严格的对齐条件：填充单元位置的任何差异都会立即导致块扩展位置的不匹配。 避免这种情况的唯一方法是两个网格产生完全相同的复制模式，只有当网格相同时才会发生这种情况。 

因此，问题简化为计算输入多重集中相同网格对的数量。 

我们可以将每个网格表示为大小固定的字符串（或位掩码）$m^2$，散列它们，计算频率，并对组合求和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力组合 |$O(n^2 m^4)$|$O(m^4)$| 太慢了|
 | 哈希+频率计数|$O(n m^2)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将每个网格视为紧凑的表示并计算相同的出现次数。 

1. 阅读每一项$m \times m$网格并将其展平为单个字符串或位掩码。 

只要一致，展平顺序并不重要，因为我们只比较精确相等。 
2. 计算每个网格表示的哈希值。 

滚动哈希或 Python 字符串元组就足够了，因为$m \le 5$，因此碰撞不是一个实际问题。 
3. 维护从网格表示到出现计数的频率图。 

每个相同的网格都贡献于同一个桶。 
4. 处理完所有网格后，计算每个桶内无序对的数量：$f \cdot (f - 1) / 2$，并对所有桶求和。 
5. 输出总计。 

### 为什么它有效

 组合操作足够严格地保留结构，使得任何两个不同的网格在至少一种组合顺序下产生不同的复制布局。 这使得交换性等同于底层网格的相等性。 一旦建立了这种等价性，问题就简化为计算多重集中的相等元素，这正是频率聚合计算的内容。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    freq = {}
    
    for _ in range(n):
        rows = []
        for _ in range(m):
            rows.append(input().strip())
        key = ''.join(rows)
        freq[key] = freq.get(key, 0) + 1
    
    ans = 0
    for c in freq.values():
        ans += c * (c - 1) // 2
    
    print(ans)

if __name__ == "__main__":
    solve()
```该实现将每个网格减少为单个长度的串联字符串$m^2$。 这避免了任何显式二维处理的需要。 频率图自动对相同的网格进行分组。 

唯一的微妙之处是确保正确处理换行符； 每个网格都被精确读取$m$行并在连接之前去除换行符。

 ## 边缘情况

 具有两个相同网格的最小输入演示了唯一的非零贡献情况。 该算法读取两者，产生相同的密钥两次，并计算$2 \cdot 1 / 2 = 1$，匹配单个有效对。 

当所有网格都不同时，每个键的频率为 1。该公式的结果为零，因为每个项$1 \cdot 0 / 2$消失，并且没有一对被计算在内。 

当出现许多相同的网格时，无论输入顺序如何，哈希表都会将它们分组到一个桶中，这表明排序不会影响结果。 对数在该桶内呈二次方增长，这与选择两个相同元素的组合结构相匹配。
