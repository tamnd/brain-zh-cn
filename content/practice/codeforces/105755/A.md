 ## 解决方案
 ## 问题理解

 我们得到一个网格，其中每个单元格都位于坐标$(i, j)$其值等于$i \times j$。 令牌开始于$(a, b)$并且必须达到$(n, m)$。 每次移动都会使行索引或列索引恰好增加 1，因此路径是单调的：仅在坐标方面向右或向上移动。 

路径的分数是所有访问过的单元格的值的总和，包括起始位置和结束位置。 任务是选择一条从开始到结束的路径来最大化这个总和。 

关键结构是路径完全由我们应用所需增量的顺序决定：我们必须执行$n-a$的增量$x$和$m-b$的增量$y$，我们正在选择这些操作的顺序。 

约束允许最多$10^4$测试用例，所有测试的总移动范围为$10^6$。 这立即表明，所有测试中的任何每步模拟组合到线性时间都是可接受的，但路径长度的任何二次模拟则不可接受。 

在网格上进行简单的 DP 是不可能的，因为坐标会上升到$10^6$，所以任何状态空间方法取决于$n \cdot m$被完全排除。 

当一个坐标已经到达其目标时，就会出现一种微妙的情况。 例如，如果$a = n$，路径被迫只增加$y$。 在这种情况下，答案是固定的。 任何贪婪策略都必须在这些强制分段下保持正确性。 

另一个重要的极端情况是两个坐标相等或提前交叉。 由于权重是乘性的，路径早期排序的微小变化可能会显着影响总和，因此必须仔细证明局部决策的合理性。 

## 方法

 暴力解决方案将考虑所需移动的所有可能序列。 有$\binom{(n-a)+(m-b)}{n-a}$这样的路径，对于每条路径，我们将模拟访问过的单元格值的总和。 这会导致路径长度呈指数增长，即使对于 30 x 30 等中等差异也是不可行的。 

更加结构化的动态规划方法定义$f(x, y)$作为可达到的最高分数$(x, y)$到$(n, m)$，有过渡$f(x,y) = x \cdot y + \max(f(x+1,y), f(x,y+1))$。 这是正确的，但网格大小使其无法使用。 

关键的观察是，每一步的决策并不是全局复杂的。 我们只选择两个连续操作的顺序：增加$x$然后$y$，或增加$y$然后$x$。 比较这两个本地交换揭示了最优策略的结构。 

如果我们比较从以下位置开始的两步序列$(x,y)$:

 序列1：$(x,y) \rightarrow (x+1,y) \rightarrow (x+1,y+1)$序列2：$(x,y) \rightarrow (x,y+1) \rightarrow (x+1,y+1)$这两条路径之间的差异仅来自于中间项：$$(x+1)y - x(y+1) = y - x$$所以序列 1 更好$y > x$，并且序列 2 更好，当$x \ge y$。 这给出了一个纯粹的局部规则：我们应该始终朝着缩小之间差距的方向前进。$x$和$y$，这意味着我们尽可能先增加较小的坐标。 

这将问题转化为确定性模拟。

 ## 算法演练

 我们模拟从$(a,b)$到$(n,m)$，始终添加当前单元格值并根据坐标之间的局部比较选择下一步移动。 

1. 开始于$(x,y) = (a,b)$，将总和初始化为0。 
2.虽然我们还没有达到$(n,m)$， 添加$x \cdot y$到答案。 这是必需的，因为每个访问的单元格在到达后立即做出贡献。 
3.如果$x = n$，我们被迫增加$y$。 移至$(x, y+1)$。 
4. 如果$y = m$，我们被迫增加$x$。 移至$(x+1, y)$。 
5. 否则，比较$x$和$y$。 如果$x \le y$， 增加$x$。 如果$x > y$， 增加$y$。 

步骤 5 背后的直觉是，首先增加较小的坐标往往比延迟它更能改善未来的产品，因为它减少了不平衡$x \cdot y$随着时间的推移做出的贡献。 

### 为什么它有效

 正确性取决于相邻动作的交换论证。 任何有效路径都可以通过交换相邻操作转换为另一条路径$X$和$Y$。 局部计算表明，当违反先前的规则时，特别是当一个步骤首先增加较大的坐标而另一个坐标较小时，交换是有益的。 重复应用这些交换会导致不存在反转的配置，这意味着只要两个移动可用，路径总是会递增较小的坐标。 此时，任何相邻交换都无法提高总和，因此该路径是最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        a, b, n, m = map(int, input().split())
        x, y = a, b
        ans = 0

        while True:
            ans += x * y
            if x == n and y == m:
                break
            if x == n:
                y += 1
            elif y == m:
                x += 1
            else:
                if x <= y:
                    x += 1
                else:
                    y += 1

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现直接反映了算法。 循环始终在移动之前处理当前单元格，确保正确包含两个端点。 边界检查$x = n$和$y = m$在贪婪比较之前完成，因为强制移动必须优先于平衡规则。 

一个常见的错误是在添加当前贡献之前更新坐标，这会改变整个总和并破坏起始单元格的正确性。

 考虑案例$(a,b) = (1,1)$和$(n,m) = (3,2)$。 

我们追踪贪心过程：

 | 步骤| x| y | x*y | 行动|
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 | x ≤ y 所以 x++ |
 | 2 | 2 | 1 | 2 | y < x 所以 y++ |
 | 3 | 2 | 2 | 4 | y ≤ x 所以 y++ |

 总计为$1 + 2 + 4 + 6 + 9 = 22$。 

该轨迹显示了算法如何保持两个坐标接近，从而避免早期出现大的不平衡。 

现在考虑一个退化的情况$(a,b) = (2,5)$,$(n,m) = (4,5)$。

 ## 边缘情况

 当一个坐标已经到达目标时，算法别无选择，只能向剩余方向移动。 例如，使用输入$(3,1)$到$(3,4)$，模拟重复应用$x=3$，所以总和变为$3 \cdot 1 + 3 \cdot 2 + 3 \cdot 3 + 3 \cdot 4$。 贪心比较永远不会以影响正确性的方式进行评估，因为每一步只存在一个合法的移动。 

当起始坐标高度不平衡时，例如$a \ll b$，算法首先增加$x$直到它赶上。 这可以防止早期与小$x$与越来越大的配对$y$值，否则在互换分析下将失去最优性。
