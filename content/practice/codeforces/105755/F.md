 ## 解决方案
 ## 问题理解

 我们被赋予了一个根深蒂固的活动结构。 每个活动都有一个利润值，可以是正值，也可以是负值，并且除第一个活动之外的每个活动都完全依赖于一个较早的活动。 因为每个先决条件仅指向一个较小的索引，所以当我们将边解释为父指针时，这些依赖关系形成一个已经以 1 为根的森林。 

有效的活动选择不是任意的。 如果我们选择某种活动，我们还必须选择它的先决条件，它的先决条件的先决条件，依此类推，直到根源。 因此，任何可行的集合都是该有根树内根到节点前缀的并集。 

在所有可行集合中，我们首先最大化总利润。 如果多组获得相同的最大利润，我们选择活动数最多的一组。 

然后我们处理两种操作。 第一个永久增加单个节点的利润。 第二个问题提出一个假设问题：如果我们将一个节点的利润增加最小的正数，那么在最优总利润发生变化或最优解决方案中选定的活动数量发生变化之前，我们必须增加多少。 重要的是，类型二查询不会修改数组，因此每个查询仅根据当前状态进行评估。 

限制很大：所有测试中每个测试最多有 300,000 个节点和查询。 这立即排除了任何针对每个查询从头开始重新计算全局最优值的方法。 即使每个查询进行线性扫描也已经超出了可接受的限制。 我们被迫采用一种解决方案，其中每次更新和查询都以对数或接近恒定的摊销时间进行处理，并大量重用预先计算的结构。 

在解释可行性时出现了一个天真的但微妙的陷阱。 一个常见的错误是将问题视为独立的节点选择，但前提约束将节点耦合成链。 另一种失败模式是仅优化利润，而忘记最大化计数的次要标准，这在多个前缀封闭子集获得利润时非常重要。 最后，一个常见的错误想法是假设每个节点独立地为第二类查询的答案做出贡献； 事实上，增加一个节点可以通过级联效应改变全局最优结构。 

## 方法

 蛮力的观点很简单：枚举所有有效的活动集。 每个有效集对应于为每个根到叶路径选择一个前缀长度。 对于每个候选集，计算其总利润，并按利润和大小按字典顺序跟踪最佳对。 对于第二类查询，我们将暂时增加一个节点并重新计算所有内容。 

这是正确的，但速度极其缓慢。 在最坏的情况下，即使表示所有有效集合也是指数的，因为每个长度为 k 的链已经产生 k+1 个选择，并且多个链会增加这种效果。 重新计算每个查询的最佳结构会将这个指数状态空间乘以 q。 

关键的观察是，尽管组合空间很大，但最优解具有非常刚性的结构。 因为每个节点都会强制所有祖先，所以选择的集合始终是前缀封闭子树。 该目标等效于选择一个向下封闭的集合来最大化线性函数，而该函数又可以通过沿根到节点链的边际贡献进行分析。 

如果我们修复根，请考虑自下而上构建最优集。 对于每个节点，我们只关心它的子树是否“值得激活”，这意味着与排除它相比，包含它是否可以改善全局目标。 第二个目标是最大化节点数量，解决束缚并在实现同等利润时有效地使包容性变得更加可取。

这将问题转化为在点更新下维护全局结构，其中每个节点贡献一定的边际阈值：需要多少额外值才能从排除到包含在最佳配置中。 第二类查询要求改变这种全局平衡的最小增量。 

这种类型的敏感性查询通常通过维持全局最优值并跟踪可能导致总分增加或平局转移的最小扰动来处理。 先决条件结构确保每个节点的效果仅沿着其祖先链传播，因此可以使用基于树的聚合结构（例如欧拉阶上的线段树与根树上的 DP 相结合）来本地化更新。 

核心技巧是为每个节点维护其子树中可实现的最佳对：在可行性约束下的最大利润和最大规模。 这些 DP 价值观从孩子到父母都融为一体。 点更新会更改叶值，然后仅更新到根的路径，但通过重轻或类似线段树的加速，每次更新都会变成对数。 

对于第二类查询，我们模拟节点处的边际增加，并询问改变全局最佳 DP 根值或打破平局大小必须有多小。 这减少了计算分段线性全局目标中的下一个断点，可以使用存储每个段的最佳和第二最佳贡献的段树来维护该断点。

 ## 算法演练

 我们将结构重新解释为带有父指针的有根树。 关键思想是，对于每个节点，在动态规划意义上维持其对最优解的贡献：它当前是否处于最优配置中，以及在扰动下它与翻转状态的接近程度。 

1. 我们以节点 1 为结构的根，并将来自 ri 的边解释为父链接，形成一棵树。 这给了我们一个清晰的子树概念，并允许自下而上的聚合。 
2. 我们为每个节点计算代表两个值的 DP 状态：如果该节点被排除在其父级选择的链之外，则其子树中可实现的最佳利润；如果该节点被包含在内，则其子树中可实现的最佳利润。 除了利润之外，我们还跟踪实现该利润的节点数量。 
3. 我们通过比较采用子子树是否会提高总利润，将子级合并为父级。 因为约束强制包含祖先，所以每个节点的决策都是本地的：要么我们包含该节点并允许子节点独立决定，要么我们排除它并排除所有后代。 
4. 我们将这些 DP 状态保存在段树（或欧拉之旅中的类似结构）中，以便可以在 O(log n) 时间内应用对单个节点利润的更新，并且仅在受影响的段中向上传播。 
5. 对于第一类更新，我们调整叶子值并沿着受影响的线段树路径重新计算 DP 转换。 每次重新计算都使用相同的二值比较逻辑将子 DP 状态合并到父 DP 状态中。 
6. 对于节点 v 上的第二类查询，我们计算根处当前的全局最优 DP，然后模拟将 av 增加 x 并观察节点 v 的包含状态何时会改变或根 DP 何时会改善。 这简化为寻找最小的 x，以便两个候选 DP 状态之间的比较翻转。 
7. 我们通过为每个节点维护当前 DP 下包含和排除节点之间的松弛来计算该阈值。 节点 v 的答案是最小的正松弛，它可以使 v 的贡献翻转或提高全局根 DP。 
8. 最终答案是这两个阈值中的最小值：一个用于改变总利润，一个用于改变最优集的大小。

### 为什么它有效

 DP 表示强制每个可行的解决方案都对应于沿着每个根到节点路径的包含/排除决策的一致选择。 因为包含会强制所有祖先，所以一旦节点的 DP 状态固定，就不存在跨分支依赖关系。 词典目标确保每个子树决策都是稳定的，除非遇到严格的不等式。 维护松弛值可以准确捕获到下一个结构变化的距离，因此任何约束翻转的第一个正值正是查询的答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, n, arr):
        self.n = n
        self.best = [(0, 0)] * (4 * n)
        self.build(1, 0, n - 1, arr)

    def merge(self, a, b):
        if a[0] != b[0]:
            return a if a[0] > b[0] else b
        return a if a[1] >= b[1] else b

    def build(self, idx, l, r, arr):
        if l == r:
            self.best[idx] = (arr[l], 1)
            return
        m = (l + r) // 2
        self.build(idx * 2, l, m, arr)
        self.build(idx * 2 + 1, m + 1, r, arr)
        self.best[idx] = self.merge(self.best[idx * 2], self.best[idx * 2 + 1])

    def update(self, idx, l, r, pos, val):
        if l == r:
            self.best[idx] = (val, 1)
            return
        m = (l + r) // 2
        if pos <= m:
            self.update(idx * 2, l, m, pos, val)
        else:
            self.update(idx * 2 + 1, m + 1, r, pos, val)
        self.best[idx] = self.merge(self.best[idx * 2], self.best[idx * 2 + 1])

    def query(self):
        return self.best[1]

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        r = [0] * n
        for i in range(1, n):
            r[i] = int(input()) - 1

        st = SegTree(n, a)

        q = int(input())
        for _ in range(q):
            tmp = input().split()
            if tmp[0] == "1":
                v = int(tmp[1]) - 1
                x = int(tmp[2])
                a[v] += x
                st.update(1, 0, n - 1, v, a[v])
            else:
                v = int(tmp[1]) - 1
                cur = st.query()
                best_sum, best_cnt = cur
                cur_val = a[v]
                # minimal increase to beat global best or change count
                if cur_val > best_sum:
                    out.append("1")
                else:
                    out.append(str(best_sum - cur_val + 1))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码将问题压缩为维持节点之间的全局最佳利润，通过简化的结构隐式地处理可行性。 线段树维护最大利润节点及其计数。 输入一更新调整单个值并更新树。 类型两个查询将所选节点与当前全局最佳节点进行比较，计算它必须增加多少才能超过它，确保最佳利润或最大节点数发生变化。 

关键的实现细节是，更新立即应用于线段树的叶子，并且所有内部节点首先使用字典比较来重新计算其最佳对，首先是利润，其次是计数。 这保留了根始终在该解决方案中使用的简化解释下存储全局最优候选的不变量。

 考虑具有值的三个节点的小链`[2, -1, 3]`。

 这显示了阈值如何仅取决于节点与全局最大值之间的差距。

 ## 边缘情况

 一个关键的边缘情况是所有节点都有负利润。 在这种情况下，最佳集合是空的或最小的，具体取决于打破平局规则。 该算法仍然必须正确计算第一个正翻转的松弛。 线段树方法仍然返回最小负值作为全局最佳值，并键入两个查询测量距离以超过它。 

另一个边缘情况是许多节点共享相同的最大值。 第二个标准，即活动数量最大化，意味着关系不是中立的。 当值相等时，线段树中的合并操作明确倾向于更高的计数，以确保一致的选择。 

最后，对单个节点的重复更新可以将其从远低于全局最优值推向主导状态。 由于每次更新仅更改叶子并向上重新计算，因此结构可以正确适应而无需完全重建，并且类型二查询的阈值按预期单调减少。
