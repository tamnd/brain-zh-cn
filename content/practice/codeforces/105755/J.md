 ## 解决方案
 ## 问题理解

 我们得到一排建筑物，每个建筑物都有一个高度和一个起始位置。 从起始建筑物开始，玩家希望最终至少踏上每座建筑物一次。 只允许在相邻建筑物之间移动。 不同之处在于，上坡移动消耗的能量等于向上变化的量，而平地或下坡移动则不消耗任何能量。 如果玩家耗尽了能量，他们就无法继续上坡。 

线路两端还设有特殊出口。 从任一端，玩家都可以自由跳出并立即返回起始建筑物并恢复原始能量。 这意味着完整的遍历可以分为多个独立的“运行”，这些“运行”始终从起始位置开始并在其中一个末端结束。 

对于每个可能的起始位置，我们需要确定最小的初始能量，以便可以使用任意数量的可重置运行来访问每个建筑物。 

这些约束意味着每个测试用例的算法接近线性时间。 由于所有测试用例中的建筑物总数最多为 100000 个，因此任何每个索引执行超过恒定工作量的解决方案都会太慢。 所有路径的二次探索或模拟能量状态立即被排除。 

天真的推理的一个微妙的失败案例是假设玩家必须执行一次连续遍历。 例如，如果高度从一开始就向两端增加，则单次行走将需要大量能量。 然而，传送允许分成两个独立的旅行，一个朝向每一端。 

另一个常见的陷阱是假设能量取决于距离或步数。 例如，与高度`[1, 100, 2]`从位置 2 开始，向左和向右移动的成本非常不同，即使双方仅相距一步。 

## 方法

 直接方法将模拟访问所有建筑物的所有可能方式。 从起始位置开始，人们可以尝试所有向左和向右移动的序列，跟踪能量和访问的状态。 这很快就会变成指数，因为每个步骤的分支和重新访问状态都取决于位置和剩余能量。 即使修剪也没有多大帮助，因为能量变化是路径相关的，并且在一条尺寸高达 100000 的线路中，可能的路径数量是巨大的。 

关键的简化来自于将任务从起始位置分解为独立的偏移。 每次我们到达终点时，能量都会重置，因此跑步不会与另一次跑步相互作用。 这意味着我们不需要一条涵盖一切的全球路径。 相反，我们可以考虑两个独立的要求：一个是从一开始就到达左端，另一个是从一开始就到达右端。 一旦两端在单独的运行中均可到达，则每个建筑物都会被覆盖，因为左侧运行会访问 1 和 s 之间的所有建筑物，而右侧运行会访问 s 和 n 之间的所有建筑物。 

因此，问题简化为计算在不对称边缘成本下单次从开始到每个结束所需的最小能量。 仅当高度增加时，从 i 移动到 i+1 才会消耗能量，反之亦然。 完整方向的成本只是沿该路径的所有上坡过渡的总和。 

因此，起始位置的答案是到达左端的成本和到达右端的成本中的最大值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 所有路径的暴力模拟| 指数| O(n) | 太慢了|
 | 前缀/后缀上坡积累 | 每次测试 O(n) | O(1) 额外 | 已接受 |

 ## 算法演练

 目标是计算每个起始指数在每个方向的最佳运动下到达两端所需的能量。 

1. 对于每个位置，计算一步步向右行走到达右端的成本。 

当从 i 移动到 i+1 时，仅当 h[i+1] - h[i] 为正时才添加。 否则什么也不加。 这捕获了沿该方向上坡移动所消耗的确切能量。 
2. 将这些累积成本存储在一个数组中，以便每个起始位置都有一个代表到达正确边界所需的总能量的值。 
3. 对于左方向，计算类似的累加，但从 i 移动到 i-1。 

当向左移动时，仅当 h[i-1] - h[i] 为正时，我们才添加 h[i-1] - h[i]，因为这代表向左移动时的上坡台阶。 
4. 将这些左方向成本存储在与起始位置对齐的另一个数组中。 
5.对于每个起始位置s，取左侧成本和右侧成本中的最大值。 这代表了左右探索是在单独的可重置运行中完成的事实，因此对于两者中更昂贵的一个来说，能量必须足够。 

这种分解有效的原因是，每个有效策略都可以重新排列，以便所有向左端的移动都发生在从一开始就只向左的运行中，而所有向右端的移动都发生在从一开始就向右的运行中。 任何切换方向的混合路径只能引入额外的上坡过渡，而不会减少任一方向所需的最大能量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        h = list(map(int, input().split()))

        # cost to reach right from each position
        right = [0] * n
        for i in range(1, n):
            gain = h[i] - h[i - 1]
            if gain > 0:
                right[i] = right[i - 1] + gain
            else:
                right[i] = right[i - 1]

        # cost to reach left from each position
        left = [0] * n
        for i in range(n - 2, -1, -1):
            gain = h[i] - h[i + 1]
            if gain > 0:
                left[i] = left[i + 1] + gain
            else:
                left[i] = left[i + 1]

        res = []
        for i in range(n):
            res.append(str(max(left[i], right[i])))

        print(" ".join(res))

if __name__ == "__main__":
    solve()
```该解决方案建立两个累积。 这`right`数组存储从起始位置向右端行走时的累积上坡成本。 只有当下一栋建筑更高时，每一步才有贡献。 这`left`数组以相反的方向反映了这个逻辑。 

每个位置的答案是通过取其两个方向成本中较大的一个来独立计算的，因为这些成本对应于两者都必须成功的单独偏移。 

一个常见的错误是尝试将两个方向合并为一个遍历成本。 这忽略了传送重置，它将旅程分成独立的部分，并消除了左右移动之间的任何耦合。 

## 工作示例

 考虑一个简单的情况，其中高度为`[1, 2, 3, 4]`。 成本只会在向右移动时累积，因为每一步都是上坡。 

| 我| 高度| 正确的成本| 剩余成本| 答案|
 | ---| ---| ---| ---| ---|
 | 0 | 1 | 0 | 3 | 3 |
 | 1 | 2 | 0 | 2 | 2 |
 | 2 | 3 | 0 | 1 | 1 |
 | 3 | 4 | 0 | 0 | 0 |

 这显示了左侧成本如何根据位置而占主导地位，因为向左移动在反向遍历中反复遇到上坡过渡。 

现在考虑`[5, 1, 4, 2]`。 

| 我| 高度| 正确的成本| 剩余成本| 答案|
 | ---| ---| ---| ---| ---|
 | 0 | 5 | 0 | 3 | 3 |
 | 1 | 1 | 3 | 4 | 4 |
 | 2 | 4 | 0 | 1 | 1 |
 | 3 | 2 | 0 | 0 | 0 |

 这表明高度不对称会根据起点导致不同的主导方向。

 ## 边缘情况

 对于完全平坦的阵列，例如`1 5 7 7 7 7 7`，每个过渡的高度增加为零。 该算法为左右累积产生零能量，并且每个起始位置都正确返回零能量，因为不需要上坡运动。 

对于起始位置处的峰，例如`1 5 3 2 4 1`从索引 3 开始，左侧可能会因为下降到返回途中上升的山谷而需要能量。 累积仅正确捕获上坡过渡，因此答案反映了两个方向爬升中较大的一个，而不是行驶的距离。 

对于严格交替的模式，例如`1 100 2 100 1`，每个方向都有多次上坡跳跃。 前缀和后缀累积独立地捕获这些尖峰，并取最大值确保起始位置考虑最差方向，而不会混合无法在单次无重置运行中遍历的路径。
