 ## 解决方案
 ## 问题理解

 我们取所有整数$1$到$n$and sort them not by numeric value but by their string representation in lexicographic order, as if they were words. 这产生了一个排列$a_1, a_2, \dots, a_n$， 在哪里$a_i$是出现在$i$此字典顺序的第 - 个位置。 

任务是计算所有位置的总和，将位置索引与那里的值进行比较，但比较是在模块化“换行”规则下完成的：每个项都有贡献$(i - a_i)$约化模数$998244353$，最后的答案取模$10^9 + 7$。 

关键的难点在于$n$可以大到$10^{12}$，因此排列太大而无法显式构造。 即使计算字典顺序中的单个位置，也需要仔细推理数字在由十进制表示形式形成的隐式前缀树中的分布方式。 

暴力方法会显式生成所有数字，按字典顺序对它们进行排序，然后计算总和。 这已经花费了$O(n \log n)$只是为了排序，在这种规模下连扫描都是不可能的。 

这些限制迫使我们从结构上推理字典顺序而不是模拟它。 

即使对于中等规模，也会出现幼稚但重要的失败案例。 例如，当$n = 12$，字典顺序为：$$1, 10, 11, 12, 2, 3, 4, 5, 6, 7, 8, 9$$字典顺序“几乎是数字顺序”的天真假设在这里立即被打破。 一旦像“1”这样的前缀主导大块，任何依赖于排序顺序的小扰动的方法都会严重失败。 

## 方法

 第一个简化来自于重写模块化表达式。 每学期$(i - a_i) \bmod M$当值变为负数时，其行为类似于带有修正的带符号差。 具体来说，它等于：$$(i - a_i) + M \cdot [i < a_i]$$因为只有当$i < a_i$减法是否环绕。 

对所有位置求和得出：$$\sum (i - a_i) + M \cdot \#\{i : i < a_i\}$$排列性质立即取消线性部分：$$\sum i = \sum a_i$$所以整个表达式简化为：$$M \cdot \#\{i : i < a_i\}$$现在我们重新解释这个条件。 自从$i$的字典顺序是$a_i$，我们可以重写：$$i < a_i \iff \text{rank}(x) < x$$所以任务变成了计算有多少个整数$x \in [1,n]$出现在字典顺序中的位置严格小于其数值。 

此时，蛮力需要计算每个的字典顺序$x$，它本身就是$O(\log n)$在数字 trie 结构上使用前缀计数。 这已经导致$O(n \log n)$，仍然不可能$10^{12}$。 

关键的结构观察是字典顺序完全由数字树中的前缀扩展驱动。 每个节点对应一个前缀$p$表示数字的区间：$$[p, p+1), [p0, p0+1), \dots$$字典序遍历正是对这棵树的 DFS。 

一个数的排名$x$取决于在到达之前访问了该前缀树中的多少个节点$x$。 重要的是，这个排名不同于$x$仅由于前缀“skips”，其中整个子树按字典顺序出现较早，但在数字上相距很远。 

我们不是单独计算每个排名，而是翻转视角：我们计算字典遍历“领先于”数字排序的频率。 当我们尽早进入深层前缀子树时，就会发生这种情况。 可以通过计算每个数字边界之前有多少个完整的子树来聚合该贡献。 

这导致基于数字的计数过程超过 10 的幂，其中每个前缀级别贡献可预测的词典位移量。 

最终的表达式可以计算为数字长度的总和，跟踪有多少数字通过字典前缀扩展“向前拉”。 这可以评估为$O(\log n)$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(n \log n)$|$O(n)$| 太慢了 |
 | 最优（数字树上的前缀计数）|$O(\log n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 将表达式从模形式重写为校正计数形式。 每个学期的贡献$M$恰好当数字的字典位置小于数字本身时。 
2. 将问题简化为计算整数$x \in [1,n]$使得字典顺序为$x$严格小于$x$。 
3. 将字典顺序解释为数字前缀树的遍历。 每个前缀$p$表示按字典顺序连续出现的连续数字块。 
4. 观察排名差异完全来自整个子树的访问早于其数字范围所建议的时间。 
5. 不是单独计算排名，而是计算所有前缀中存在多少个这样的“早期访问”位置。 每个前缀的长度$k$贡献一个大小的块$10^{k}$, 截断为$n$。 
6. 累积所有前缀深度的贡献。 在深度$k$，完整块的数量是$\lfloor n / 10^k \rfloor$，它表示存在多少个该比例的完整前缀间隔。 
7. 将这些贡献求和以获得字典顺序和数字顺序之间的倒置总数。 
8. 将最终计数乘以$M = 998244353$，然后减少模数$10^9+7$。 

### 为什么它有效

 词典顺序与数字顺序的不同之处仅在于由前缀引起的整个连续数字块的重新定位。 每个这样的重定位都对应于移动块内所有数字的一致偏移量。 计算每个数字级前缀导致这种位移的次数，可以准确地计算字典顺序低于其数字标识的数字集。 十进制表示的结构确保这些贡献在前缀深度上是不相交的，因此对 10 的所有幂求和可以准确地捕获每个差异一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
M = 998244353

def solve():
    n = int(input().strip())

    # Count how many times lexicographic traversal jumps ahead of numeric order.
    # This is captured by contributions from each decimal scale.
    cnt = 0
    power = 10

    while power <= n:
        cnt += n // power
        power *= 10

    ans = (cnt % MOD) * (M % MOD) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```该实现依赖于这样的观察：10 的每个幂都会在字典前缀树中引入一个新层。 商$n // 10^k$计算存在多少个该规模的完整块，并将它们相加$k$聚合所有词典“早期跳跃”。 

乘以$M$直接来自于原始表达式中的负差异引入的模校正。 

## 工作示例

 ### 示例 1

 输入：```
3
```为了$n = 3$，没有超出个位数的有意义的十进制前缀跳跃，因此 10 的更高次方的所有贡献均为零。 

| 电源 | n // 功率 | 累计碳纳米管|
 | ---| ---| ---|
 | 10 | 10 0 | 0 |

 结果是$0 \cdot M = 0$。 

这证实了当词典顺序和数字顺序在小范围内重合时，不会引入任何校正。 

### 示例 2

 输入：```
12
```这里的字典顺序是：$$1, 10, 11, 12, 2, 3, 4, 5, 6, 7, 8, 9$$| 电源 | n // 功率 | 累计碳纳米管|
 | ---| ---| ---|
 | 10 | 10 1 | 1 |
 | 100 | 100 0 | 1 |

 所以cnt = 1。 

这一单一贡献对应于从 1 开始的整个块，将三位数结构拉到后面的数字之前，恰好创建一个字典顺序小于数值的实例。 

于是答案就变成了$M$。

 ## 边缘情况

 当$n = 1$，字典顺序与数字顺序相同，因此没有位置$i < a_i$。 10 的幂循环永远不会执行，结果正确地为零。 

什么时候$n$是 10 的幂，词典结构正好引入一个新的全前缀层，商$n // 10$干净地捕捉到了这一点。 

什么时候$n$有混合数字，如999999999999，每个10次方层独立贡献。 该算法累积所有此类贡献而不会重复计算，因为每个数字范围对应于不相交的前缀分区。
