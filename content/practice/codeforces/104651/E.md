 ## 解决方案
 ## 问题理解

 机器人从无限整数网格的原点开始，执行固定序列的运动命令。 每个命令都尝试将机器人沿四个基本方向之一移动一个单位。 复杂的是，一些网格单元被障碍物阻挡，但障碍物的位置我们不知道。 每当机器人尝试进入被阻挡的单元格时，它都不会移动，但命令仍被视为已消耗，并且会继续执行。 

我们只得到命令字符串，而不是障碍物配置，甚至机器人的最终轨迹。 在一些未知的障碍物位置下处理所有命令后，机器人在某个最终位置结束。 任务是确定通过在网格上的任何位置选择一组障碍物（不包括始终免费的原点）可以实现的每个可能的最终位置。 

约束 n ≤ 20 是关键的结构提示。 由于步数如此之少，路径和障碍物之间可能的交互模式总数足够小，以至于指数推理是可以接受的。 任何尝试直接在无限网格上对所有可能的障碍物配置进行建模的方法都会立即失败，因为状态空间是无界的。 相反，我们必须独立地思考路径上的哪些决策可以被“强制”或“阻止”。 

一个微妙的点是，障碍物可以任意放置，并且最初不需要存在。 我们实际上可以为每一步决定该行动是成功还是失败，只要失败可以通过在目标单元格上放置障碍来解释，并且该障碍尚未被早期选择排除。 

主要的边缘情况来自这样一个事实：阻止移动会改变机器人的位置，从而改变所有未来的移动结果。 例如，像“RU”这样的命令序列的行为会有所不同，具体取决于第一次移动是成功还是被阻止。 如果“R”被阻挡，机器人停留在(0,0)，因此“U”从(0,0)移动到(0,1)。 如果“R”成功但“U”被阻止，则我们以 (1,0) 结束。 如果两者都没有被阻塞，我们就以 (1,1) 结束。 如果两个动作都被阻止，我们将停留在 (0,0)。 这些依赖性意味着问题本质上是关于枚举分支过程中的可达状态。 

## 方法

 暴力解释将尝试模拟机器人的每种可能的障碍物配置。 由于每个网格单元都可以被阻挡或不被阻挡，因此即使对于微小的网格也是不可能的。 然而，我们实际上并不需要考虑任意的​​障碍物集； 只有在执行期间尝试作为目标的单元才重要。 最多有 n 次这样的尝试移动，因此只有 n 个位置可以成为“关键”阻挡者。 

更结构化的暴力是将每个命令视为一个决定：要么移动成功，要么被阻止。 如果成功，我们更新位置； 如果失败，我们就留在原地。 这表明随着时间步长的状态 (i, x, y) 的递归，但仅此还不够，因为阻止移动需要目标单元被标记为有障碍物，并且一旦单元被用作障碍物，它应该一致地阻止所有未来对同一坐标的访问。 这在整个序列中引入了全局一致性约束。

关键的见解是我们不需要明确地跟踪任意障碍物集。 相反，我们只需要知道哪些细胞被之前的决定“激活为障碍”。 由于 n 最多为 20，因此机器人可以沿着任何执行路径尝试最多 20 个不同的目标位置。 任何有效的障碍物配置完全由这些尝试位置的子集确定。 因此，我们可以预先计算沿着完全成功的行走尝试的坐标序列，然后探索这些坐标的哪个子集被视为被阻止。 

这导致了一个模拟观点：我们首先计算标称路径，假设所有移动都成功，记录每个中间目标单元。 然后，我们对这些单元的子集执行深度优先搜索，决定每一步移动是否被阻止，通过检查当前目标是否已在分支中较早地被声明为阻止来确保一致性。 

这将问题简化为探索大小最多为 2^n 的状态空间，这对于 n ≤ 20 是可行的。

 ## 算法演练

 我们从左到右处理命令字符串，同时保持机器人的当前位置。 在每一步中，如果执行移动，我们都会考虑下一个目标单元格。 

1. 我们定义一个递归函数，表示当前步骤索引、当前位置和迄今为止选择的一组块坐标。 这种状态完全决定了所有未来的行为，因为唯一的不确定性来自下一个目标单元是否被阻止。 
2. 在步骤 i，我们使用第 i 个命令从当前位置计算预期的下一个位置 (nx, ny)。 
3. 仅当该坐标在当前状态下尚未被强制阻塞时，我们才分为两种情况。 第一种情况假设移动成功，因此我们从 (nx, ny) 继续执行步骤 i+1。 
4. 第二种情况假设移动被阻止，只有当我们决定将 (nx, ny) 标记为障碍物时，这才有效。 在这种情况下，位置保持不变，我们继续执行步骤 i+1，同时记录该坐标现在已被阻止，以便在后续步骤中保持一致。 
5. 当我们到达步骤 n 时，我们将最终位置记录为一个可能的结果。 

一个关键的优化是我们不需要在复杂的结构中显式存储完整的阻塞单元集。 由于 n 很小，我们可以将阻塞决策编码为步骤索引上的位掩码，因为每个步骤最多对应于该分支中的一个候选阻塞坐标。 

### 为什么它有效

 在每一步中，算法都会精确地模拟仅有的两种物理上有意义的移动可能性：要么机器人成功进入目标单元，要么因为该单元被阻挡而无法进入。 任何有效的障碍物配置都对应于为每个步骤选择阻止哪些尝试目标。 因为障碍物只有在与尝试的目的地重合时才重要，因此有关网格的其他信息不会影响结果。 这在 DFS 中的一致决策模式与机器人在某些障碍物放置下的有效执行之间建立了一对一的对应关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

dirs = {
    'L': (-1, 0),
    'R': (1, 0),
    'D': (0, -1),
    'U': (0, 1)
}

def solve():
    n = int(input().strip())
    s = input().strip()

    targets = []

    def dfs(i, x, y, blocked):
        if i == n:
            return {(x, y)}

        dx, dy = dirs[s[i]]
        nx, ny = x + dx, y + dy

        res = set()

        if (nx, ny) not in blocked:
            res |= dfs(i + 1, nx, ny, blocked)

        new_blocked = set(blocked)
        new_blocked.add((nx, ny))
        res |= dfs(i + 1, x, y, new_blocked)

        return res

    ans = dfs(0, 0, 0, set())

    ans = sorted(ans)
    print(len(ans))
    for x, y in ans:
        print(x, y)

if __name__ == "__main__":
    solve()
```代码直接遵循前面描述的递归结构。 函数 dfs 表示命令序列的部分执行，其中 block 存储已被确定为当前分支中的障碍的所有坐标。 在每一步中，我们都会根据该坐标被视为空闲还是阻塞来计算下一个预期坐标和分支。 

关键细节是阻塞在分支内是不可逆的，这就是我们将复制集传递到递归调用中的原因。 这确保了一致性：一旦坐标被声明为阻塞，后面的每个步骤都会尊重它。

 ## 边缘情况

 一种重要的边缘情况是，移动目标是同一路径中先前已访问过的坐标。 例如，在“LR”中，第二个命令尝试返回到(0,0)。 如果在正确的时间选择该单元作为障碍物，机器人可能会卡在原地，产生与天真的取消直觉所暗示的不同的最终分布。 DFS 可以正确处理此问题，因为它独立地处理每个尝试的坐标，无论之前是否访问过该坐标。 

另一个微妙的情况是通过不同的步骤重复定位同一坐标。 由于阻塞集在递归分支中持续存在，因此一旦坐标被标记为阻塞，它就会始终阻塞所有未来的尝试，确保像“R L R L”这样的循环不会意外地允许不一致的部分阻塞。
