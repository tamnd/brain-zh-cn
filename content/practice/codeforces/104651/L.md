 ## 解决方案
 ## 问题理解

 我们得到了一系列菜肴，每道菜都有两个独立的值。 第一个值代表其正常成本，第二个值代表额外的“活动附加费”，该附加费不是按菜品支付，而是每次选择支付一次，等于所有所选菜品中的最高附加费。 

对于任意固定数量的所选菜肴$k$，我们必须准确选择$k$独特的菜肴。 总成本是其正常价格加上等于其中最大事件价格的单个额外条款的总和。 任务是计算每种可能的最小可实现总成本$k$从 1 到$n$。 

困难在于，附加费通过极大值运算将所有选择的项耦合起来，因此一项的贡献取决于它是否成为最大值$b_i$在选定的子集中。 

约束条件$n \le 200{,}000$迫使任何解决方案接近线性或$n \log n$。 任何涉及检查所有子集甚至所有对的事情都是立即不可行的，因为选择$k$项目已经导致指数组合，甚至是天真的$O(n^2)$每$k$方法将导致大致$10^{10}$运营。 

当只贪婪地思考时，就会出现一个微妙的问题$a_i$。 例如，选择最小的$a_i$值并不总是最佳的，因为稍差一些$a_i$可能会带有一个小得多的$b_i$，显着降低最终的最高附加费。 

当总是选择最小的时，会出现第二种失败情况$b_i$。 这最大限度地减少了附加费，但忽略了所选项目的集合必须随$k$，以及之间的最佳权衡$a_i$和$b_i$随着子集大小的增长而变化。 

## 方法

 强力策略是枚举大小的所有子集$k$, 计算$\sum a_i$和最大$b_i$，并取最小值。 甚至仅限于一个$k$， 这是$\binom{n}{k}$，并对所有内容求和$k$是指数的$n$，所以这是不可行的。 

稍微结构化一点的蛮力可以最大程度地修复该项目$b_i$在子集中。 如果我们假设一道特定的菜$x$提供最高附加费，那么我们只从有附加费的菜品中选择其他菜品$b_i \le b_x$，我们选择最便宜的$k-1$经过$a_i$。 这减少了每个问题$x$，但仍然导致$O(n^2 \log n)$如果直接完成，情况会更糟。 

关键的观察是最大的身份$b_i$在尺寸的最佳解决方案中$k$不是任意的。 如果我们按以下顺序对菜肴进行排序$b_i$，并将每道菜视为潜在的“最大边界”，那么所有具有最大边界的有效选择$b_i = b_j$必须来自前缀直到$j$。 在该前缀内，我们要选择$k-1$最小的项目$a_i$。 

这表明维持越来越多的候选人$b_i$，同时动态跟踪最小的总和$k-1$的值$a_i$。 对于每个位置$j$，如果我们对待$b_j$作为最大值，我们需要尽可能最佳的子集大小$k-1$来自之前的元素。 

维护“最小总和”的标准工具$k$“插入下是一对堆或平衡结构：一个结构保存所选的最小元素，另一个结构保存其余元素。当我们扫描增加时$b_i$，对于每个可能的子集大小，我们可以维护$a_i$并将其与当前的相结合$b_i$。 

关键的重新表述是对于排序依据中的每个前缀$b$顺序，我们计算精确选择的最佳总和$t$项目由$a$，然后与当前的相结合$b$作为候选答案$k = t+1$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(1) | O(1) | 太慢了|
 | 带堆/选择维护的前缀 DP |$O(n \log n)$| O(n) | 已接受 |

 ## 算法演练

 1. 按活动价格对所有菜肴进行排序$b_i$按非递减顺序。 这样保证了我们处理一道菜的时候，它是最大的$b$我们目前允许选择。 这将全局最大约束转换为前缀约束。 
2. 维护一个跟踪最小可能总和的结构$a_i$为了准确选择$t$已处理前缀中的项目。 从概念上讲，我们想知道，对于每个$t$，最小总和是多少$a$-我们仅使用第一个即可实现的值$i$项目。 
3. 当我们迭代排序的菜肴时，我们通过获取或跳过当前项目来更新这些最小总和。 这就像前缀上的背包一样，但利用成本只是累加性并且我们关心精确计数这一事实进行了优化。 
4. 对于每个前缀位置$i$,解读当前菜品$i$作为最大值$b$在候选解决方案中。 对于每一个可能$k$，我们结合：

 的最佳总和$k-1$ $a$- 之前前缀的值$i$，加上$a_i + b_i$。 

这反映了选择$k$项目，其中$i$是最大值$b$-贡献者。 
5. 维护一个全局答案数组，其中每个答案$k$存储最大元素的所有选择中的最小值。 
6.返回所有答案$k$。 

### 为什么它有效

 修复某些问题的最佳选择$k$。 让$x$是最大的项目$b$在那次选择中。 根据定义，所有其他选定的项目必须来自具有$b_i \le b_x$，它完全对应于排序顺序中的前缀。 在该前缀中，选择剩余的最好方法$k-1$项目独立地最小化它们的总和$a_i$，因为附加费已经固定为$b_x$。 该算法枚举了所有可能的选择$x$，并且对于每一个都考虑最佳伴随集，因此不会错过最佳解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    items = []
    for _ in range(n):
        a, b = map(int, input().split())
        items.append((b, a))

    items.sort()

    INF = 10**30
    dp = [INF] * (n + 1)
    dp[0] = 0

    ans = [INF] * (n + 1)

    for b, a in items:
        for k in range(n, 0, -1):
            if dp[k - 1] + a < dp[k]:
                dp[k] = dp[k - 1] + a

        for k in range(1, n + 1):
            if dp[k - 1] < INF:
                ans[k] = min(ans[k], dp[k - 1] + a + b)

    for k in range(1, n + 1):
        print(ans[k])

if __name__ == "__main__":
    main()
```该计划首先根据活动成本对菜肴进行排序，这是使最大程度的运营易于管理的结构转变。 DP 阵列`dp[k]`表示精确选择时基本价格的最小可能总和`k`当前前缀中的项目。 

反向循环结束`k`对于防止在一次迭代中多次重复使用同一项目，保留 0-1 选择属性是必要的。 每次更新都会考虑包括当前菜肴的`a`值分成不同大小的子集。 

第二个循环计算贡献，其中当前项被视为最大值$b$。 我们结合其$a + b$具有最佳尺寸子集的成本$k-1$已经可以实现`dp`。 

最终答案数组存储最大元素的所有选择中的最佳值。

 ## 边缘情况

 一个关键的边缘情况是当具有最小的项目$b_i$有一个非常大的$a_i$。 在这种情况下，小规模的最优解决方案$k$完全避免它，但它可能与更大的$k$由于选择有限。 

例如：```
3
100 1
1 10
1 10
```什么时候$k=1$，我们选择具有成本的项目$1 + 10 = 11$。 什么时候$k=2$，我们选两个小的$a$物品和付款$2 + 10$。 该算法通过允许不同的项目作为最大值来正确处理这个问题$b$并为每种情况独立地重新计算子集和。 

DP 确保即使性能不佳$a_i$存在非常小的$b_i$，它不会污染较小的子集大小，因为每个前缀和每个最大选择都会重新计算贡献。
