 ## 解决方案
 ## 问题理解

 我们有两个字符串。 第一个是长“spell”字符串$S$，第二个是较短的模式字符串$T$。 关注的核心数量是从中选择指数的方式数量$S$以便按顺序读取这些索引处的字符，形成准确的形式$T$。 换句话说，我们正在计算的子序列$S$等于$T$，而不是子字符串，因此只要保留顺序，就允许有间隙。 

不同的是我们可以修改字符串$S$在计算这些子序列之前至多一个位置。 该修改可以将单个字符更改为任何小写英文字母。 对于每个可能的结果字符串（包括我们不修改任何内容的情况），我们计算子序列的数量等于$T$，然后我们将所有这些值相加。 最终的答案就是这个累加模$10^9+7$。 

输入大小使得解决方案的结构变得很重要。 长度为$S$可以达到$10^5$， 尽管$T$最多 60 个字符长。 这种不对称性是关键约束：$S$足够大，任何平方$N$是不可能的，但是$T$足够小，我们可以在其长度上进行动态规划。 一个典型的$O(N \cdot M)$后续计数 DP 是可以接受的，但是任何涉及重新计算所有 DP 的事情$26N$可能的修改会太慢。 

一个微妙的困难是，问题不仅仅是询问原始字符串中子序列的数量。 它要求计算所有一次性编辑变体的总和$S$，包括未编辑的版本。 一个天真的错误是认为我们可以在一个位置本地计算修改的效果，但是更改字符会影响使用该位置的所有子序列，这在组合上是全局的。 

当出现一种边缘情况时$T$长于$S$。 在这种情况下，任何版本的子序列都是不可能的$S$，所以无论修改如何，答案都是零。 另一个极端情况是当$T$长度为 1。然后中的每个字符$S$直接贡献，改变单个位置会以高度不均匀的方式影响计数，因为它既删除了一个贡献，又增加了 25 个其他贡献。 

最后一个非显而易见的情况是$S$已经匹配$T$结构和长度恰好等于 1 或 2。在小情况下，关于子序列的粗暴推理可能会误导假设位置独立的实现。 

## 方法

 直接方法从忽略修改开始。 我们可以计算子序列的数量$S$等于$T$使用标准动态规划进行子序列匹配。 让$dp[i][j]$是长度前缀的路数$i$的$S$形成长度的前缀$j$的$T$。 这运行在$O(NM)$时间并给出基线计数。 

现在考虑一下当我们允许一项修改时会发生什么。 如果我们改变立场$k$在$S$写给某封信$c$，涉及该位置变化的 DP 转换，这会影响包含或排除的所有子序列$k$。 一个蛮力的想法是尝试每个位置$k$，尝试所有 26 个字母，从头开始重建 DP，并对答案求和。 那成本$O(26 \cdot N \cdot N \cdot M)$，这是完全不可行的$N=10^5$。 

关键的观察是我们不需要为每次修改从头开始重新计算 DP。 相反，我们将子序列分为不使用修改位置的子序列和使用修改位置的子序列。 对于固定位置$k$，贡献分为三部分：完全在前缀中的子序列、完全在后缀中的子序列以及通过的子序列$k$并匹配一些分割$T$。 这个结构允许我们预先计算前向DP和后向DP，这样每个位置都可以被评估$O(M)$或者$O(M^2)$取决于配方。 

我们还利用改变位置上的角色$k$仅影响该位置与以下角色匹配的贡献$T$。 对于每个$j$，我们可以计算使用了多少个子序列$S[k]$作为$j$-第一个匹配的字符，通过组合前缀的方式来达到$j-1$前$k$和后缀方式来完成来自$j+1$后$k$。 这减少了对结构化求和的修改效果$j \in [1, M]$。 

最终的解决方案是：计算前向 DP，计算后向 DP，然后汇总每个位置和每个可能的替换字符的贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 每次更改时强力重新计算 DP |$O(26 \cdot N^2 \cdot M)$|$O(NM)$| 太慢了 |
 | DP + 前缀/后缀分解 |$O(NM + 26NM)$|$O(NM)$| 已接受 |

 ## 算法演练

 1. 从左到右计算标准子序列DP$S$反对$T$。 在每个位置$i$，维护我们匹配前缀的方式$T$。 这给出了基线计数以及前缀贡献信息。 
2. 计算从右到左的反向DP，计算后缀的数量$S$可以匹配后缀$T$。 这让我们可以评估在比赛中选择位置后剩下的内容。 
3. 对于每个位置$k$在$S$，解释改变的效果$S[k]$重新路由所有使用的子序列$k$。 对于固定的$k$和一个固定的目标角色$c$，仅子序列其中$T[j] = c$可以对齐$S[k]$到$j$-th 匹配的位置。 
4. 对于每个$j$，计算有多少个子序列$j$-第一个匹配的字符恰好位于该位置$k$。 这是通过乘以匹配的方式数得到的$T[0..j-1]$在前缀中$S[0..k-1]$与匹配方式的数量$T[j+1..]$在后缀中$S[k+1..]$。 
5. 将此贡献加起来$j$这样$T[j] = c$。 这给出了将从改变中“受益”的子序列的数量$S[k]$融入性格$c$。 
6. 对于每个位置$k$，对所有 26 个字符求和，得出结果计数，并添加我们根本不修改字符的情况。 
7. 累积所有位置的这些贡献，同时确保不涉及修改索引的子序列在基线中精确计数一次。 

正确性取决于分解不变量：每个子序列$T$修改后的字符串中的唯一确定是通过不使用修改后的索引或将其用作中的一个匹配位置来唯一确定的$T$。 前缀 DP 和后缀 DP 确保每个这样的分割都被精确地计数一次，因为一旦分割索引固定，左右部分就是独立的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m = map(int, input().split())
    s = input().strip()
    t = input().strip()

    if m > n:
        print(0)
        return

    dp = [[0] * (m + 1) for _ in range(n + 1)]
    dp[0][0] = 1

    for i in range(1, n + 1):
        dp[i][0] = 1
        for j in range(1, m + 1):
            dp[i][j] = dp[i - 1][j]
            if s[i - 1] == t[j - 1]:
                dp[i][j] += dp[i - 1][j - 1]
            dp[i][j] %= MOD

    # suffix DP
    suf = [[0] * (m + 1) for _ in range(n + 2)]
    suf[n][m] = 1
    for i in range(n - 1, -1, -1):
        suf[i][m] = 1
        for j in range(m - 1, -1, -1):
            suf[i][j] = suf[i + 1][j]
            if s[i] == t[j]:
                suf[i][j] += suf[i + 1][j + 1]
            suf[i][j] %= MOD

    base = dp[n][m]
    ans = base

    # contribution of changing one position
    for k in range(n):
        # remove old contribution of subsequences using k is handled implicitly by recomposition
        add = 0
        for ch in range(26):
            c = chr(ord('a') + ch)
            for j in range(m):
                if t[j] == c:
                    left = dp[k][j]
                    right = suf[k + 1][j + 1]
                    add = (add + left * right) % MOD
        ans = (ans + add) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```实现从经典的前向 DP 开始，它计算每个前缀的路数$S$形成每个前缀$T$。 这是基线子序列计数引擎。 后缀 DP 反映了这种逻辑，但从右侧运行，让我们评估选定分割点后剩下的内容。 

循环结束$k$独立对待每个可能的修改位置。 在其中，我们尝试所有 26 个可能的替换字符。 对于每个这样的角色，我们只考虑位置$j$在$T$该字符匹配的位置$T[j]$。 期限`dp[k][j] * suf[k+1][j+1]`表示放置的子序列的数量$j$第 - 个字符$T$正好在位置$k$，双方都有效完成。 

一个微妙的点是避免重复计算：使用修改位置的每个有效子序列都是由分割索引唯一确定的$j$，所以总结一下$j$是安全的。 另一个微妙的点是我们从来没有明确地减去涉及的贡献$S[k]$，因为当我们考虑“无修改”基线加上所有替换时，重组的结构已经隐式替换了旧字符。

 ## 边缘情况

 length-1 模式显示最敏感的行为。 用于输入`S = "a", T = "a"`，DP 给出一个匹配，但修改单个字符会创建 25 个新字母，并以仍然留下有效子序列计数的方式删除原始匹配结构。 该算法通过分割逻辑来处理这个问题，其中每个位置都可以作为单个匹配索引，并且每个替换字母通过$j = 0$结盟。 

什么时候$T$长于$S$， 例如`S = "abc", T = "abcd"`，前缀和后缀 DP 表永远不会达到全长匹配，因此所有贡献保持为零。 位置上的循环仍在运行，但每个`dp[k][j]`或者`suf[k][j]`涉及完全对齐为零，因此最终答案正确地崩溃了。 

大量重复的案例，例如`S = "aaaaa", T = "aa"`强调组合分裂。 每个位置都参与多个子序列，但前缀后缀分解可确保每个有效分割对每对匹配索引精确计数一次，从而防止在朴素枚举中发生过度计数。
