 ## 解决方案
 # 问题理解

 该问题对每次操作后减少相同乘法因子的值进行建模。 加图诺从心脏大小开始`H1`。 每咬一口后，当前的心脏大小就会乘以`(B - 1) / B`，因此每次操作都会使该值变小。 我们需要找到所需的最小咬数，直到心脏大小达到最大`H2`。 

输入包含许多独立的案例。 每个案例都给出了起始值、目标值以及控制每次值收缩多少的残酷因子。 输出是最小乘法次数`(B - 1) / B`达到目标所需的。 

测试用例的数量可以大到`100000`，因此模拟每一口的解决方案是不可能的。 在最坏的情况下，答案可能是数百万次操作。 尽管对于一种情况来说数百万次迭代听起来是可以管理的，但将其乘以`100000`给出了太多的操作。 我们需要一个针对每个测试用例只执行少量固定工作的解决方案。 

的价值观`H1`可以大到`10^12`，这排除了使用浮点运算重复存储和更新心脏值的方法。 经过多次运算后，该值会变得很小，并且重复乘法会累积精度误差。 我们需要直接处理数学关系。 

一个常见的错误是忘记答案是第一次该值**小于或等于**`H2`，并非严格意义上的更少。 例如：```
1
100 50 2
```咬一口后的值正好是`50`，所以答案是`1`。 仅检查以下值的实现`H2`会错误地返回`2`。 

当减少非常缓慢时，会出现另一种边缘情况。 例如：```
1
1000 1 10
```因素是`0.9`，因此该值逐渐减小。 答案是`66`。 假设答案很小或尝试固定次数的迭代的解决方案将在这里失败。 

最终的精度边缘情况是当数学答案非常接近整数时。 例如：```
1
100 99 100
```比例很小，所以咬的次数很大。 用对数计算答案可以产生如下值`100.00000000001`而不是确切地`100`。 如果我们盲目申请`ceil`，我们可能会多算。 

# 方法

 The direct approach is to simulate the process. 开始于`H1`, 反复乘以`(B - 1) / B`，并计算我们执行此操作的次数，直到该值不再大于`H2`。 这显然是正确的，因为它完全遵循流程。 

问题在于操作次数。 单个测试用例的最大答案约为数百万，并且可能有`100000`测试用例。 进行模拟总体上需要太多的乘法。 

关键的观察是重复的乘法形成了一个几何序列。 后`n`咬，其值为：`H1 * ((B - 1) / B)^n`我们需要最小的`n`这样：`H1 * ((B - 1) / B)^n <= H2`我们可以使用对数来解决这个不等式，而不是生成所有中间值。 取对数将指数转换为乘法：`n * log((B - 1) / B) <= log(H2 / H1)`因为底座介于`0`和`1`，对数为负，因此除法时不等式方向发生变化。 重新排列给出：`n >= log(H2 / H1) / log((B - 1) / B)`满足条件的最小整数就是该值的上限。 

浮点精度需要进行小的修正。 计算出候选答案后，我们通过使用对数检查附近的整数来在本地验证它。 这可以避免由非常接近整数边界的值引起的错误。

 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于每个测试用例，使用几何级数公式计算答案的对数估计。 

该表达式给出一个实数，表示穿过目标的确切点。 由于我们需要整数的咬数，因此答案必须是不低于该值的最小整数。 
2. 将估计值向上舍入以获得候选答案。 

这处理正常情况，其中浮点舍入给出的值略低于真实边界。 
3. 通过再次比较对数表达式来检查候选值周围的一些值。 

浮点精度唯一可能出现的错误是相差一位。 测试附近的值可以修复这个问题，而无需缓慢的模拟。 
4. 返回第一个满足不等式的检查值。 

这保证了返回最小的有效咬数。 

原理：心脏大小的顺序恰好是几何级数。 对数变换给出了有效和无效咬合数之间的精确数学边界。 校正步骤仅解决数值表示问题，而底层比较仍然遵循原始不等式。 

# Python 解决方案```python
import sys
import math

input = sys.stdin.readline

def solve_case(h1, h2, b):
    # Need the smallest n where:
    # h1 * ((b - 1) / b)^n <= h2

    ratio_log = math.log((b - 1) / b)
    need_log = math.log(h2 / h1)

    ans = math.ceil(need_log / ratio_log)

    def ok(x):
        return math.log(h1) + x * ratio_log <= math.log(h2) + 1e-15

    while ans > 0 and ok(ans - 1):
        ans -= 1

    while not ok(ans):
        ans += 1

    return ans

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        h1, h2, b = map(int, input().split())
        out.append(str(solve_case(h1, h2, b)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现首先将几何级数条件转换为对数不等式。`ratio_log`存储收缩因子的对数，并且`need_log`存储目标比率的对数。 

最初的`ceil`立即给出一个接近的答案。 两个 while 循环只是小的修正。 它们处理浮点算术将计算值放在整数边界的错误一侧的情况。 

比较使用对数而不是计算实际的心脏值。 直接乘法需要在多次咬合后处理非常小的浮点数，并且可能会损失精度。 

这`1e-15`margin 可以防止数学上应该相等的值因为微小的浮点噪声而被拒绝。

 # 边缘情况

 对于确切的目标情况：```
1
500 500 2
```对数公式将产生零，因为不需要收缩。 算法返回`0`立即通过数学条件。 它从不进行不必要的咬合。 

对于平等边界：```
1
100 50 2
```咬一口后的表情一模一样`50`。 验证步骤检查`<=`，所以候选人`1`仍然有效。 严格比较会错误地增加答案。 

对于非常缓慢的收缩：```
1
1000 1 10
```比例为`0.9`，这意味着每次操作仅删除当前值的百分之十。 该算法避免了数百万次重复乘法并直接计算交叉点。 

对于精度敏感的值：```
1
100 99 100
```数学答案接近于整数。 初始对数估计可能稍微不准确，但最终校正会检查相邻值并移动到真正的最小有效答案。
