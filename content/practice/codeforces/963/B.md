 ## 解决方案
 ## 问题理解

 我们得到一棵树，其中每个顶点都有一个关联的当前度数，该度数随着顶点的删除而变化。 仅当我们选择顶点时其度数为偶数时，该顶点才有资格被删除。 当移除一个顶点时，所有关联边都会消失，因此其邻居的度数会减少。 

任务是确定是否存在删除每个顶点的删除序列，始终遵守所选顶点当前必须具有偶数度的规则。 如果存在这样的序列，我们必须输出一个有效的订单。 

输入表示是树的有根描述：每个顶点 i 要么连接到父节点 p[i]，要么在 p[i] 等于 0 时为根。 这定义了一个具有 n 减 1 条边的无向树。 该过程本身是动态的，因为删除顶点会改变全局的度数，因此局部决策会影响未来的可用性。 

约束 n 最大为 2 · 10^5 意味着任何解决方案都必须接近线性或线性算数。 任何重复重新计算度数或通过每步更新邻接列表来模拟幼稚移除的操作都会在密集交互模式中面临二次行为的风险。 尝试所有可能订单的解决方案是阶乘的，并且立即不可能。 

一些故障模式自然会出现。 

如果我们不仔细维护可用节点的结构，重复删除任何当前偶数度节点的贪婪策略可能会失败，因为局部偶数顶点可能会通过破坏子树中的奇偶校验结构来阻止未来的进展。 

如果我们假设奇偶校验是独立的，则会出现第二个微妙的故障：删除节点会更改所有邻居的奇偶校验，因此本地选择可以将许多节点从偶数翻转为奇数，反之亦然。 即使存在有效的全局排序，忽略这种依赖性也会导致死胡同。 

例如，考虑三个节点 1-2-3 的简单路径。 最初度数为 1, 2, 1。删除节点 2 是有效的，因为度数是偶数，留下两个孤立的节点，这两个节点是可以轻松移除的。 相反，如果我们首先移除一片叶子而不考虑奇偶校验进化，那么我们可能会因为较大树中的顺序而陷入困境。 

核心困难不是检查可移除性，而是选择一个保留完成所有移除可能性的顺序。 

## 方法

 暴力方法将尝试模拟所有可能的删除序列。 在每一步中，我们选择任意度数为偶数的顶点并进行递归。 由于最初存在多达 n 个选择，并且每次删除都会改变结构，因此状态空间本质上是顶点的排列，在最坏的情况下给出 O(n!) 的可能性。 即使进行了修剪，分支仍然是指数级的，因为奇偶校验约束不能及早消除足够的分支。 

关键的观察结果是，问题本质上是关于树中的奇偶校验传播。 删除一个顶点会翻转其所有邻居的奇偶校验。 这意味着我们不是在跟踪精确的度数，而是在跟踪哪些顶点当前是偶数，以及该集合在沿边的切换下如何演变。 

关键的结构见解是树允许自下而上的消除策略：叶子可以以受控的方式处理，因为它们最初具有1度，并且只有在其父级被移除或奇偶校验翻转通过相邻删除传播后才可移除。 这表明按照与后序遍历一致的顺序处理顶点，但实际情况是动态奇偶性，而不是静态度。

一种更精确的看待它的方法是考虑贪婪减少，即我们重复删除任何叶子，即使在考虑了先前的删除之后，其当前状态也会变为当前状态。 当叶子被移除时，它只会影响其父节点，即树中唯一剩余的邻居。 这使得更新本地化且易于管理。 

我们在保持当前程度的同时模拟移除。 每次删除一个顶点时，我们都会更新其父顶点的度数，并可能使其重新符合条件。 如果我们总是处理新的符合条件的顶点，我们就会以反映有效消除序列的建设性顺序的方式有效地向上传播删除。

 ## 算法演练

 1. 从父数组构建树的邻接结构。 我们还计算每个节点的初始度。 这是必要的，因为可移除性取决于当前程度的奇偶性，而不仅仅是结构。 
2. 初始化一个队列，其中包含当前度数为偶数的所有顶点。 这些是唯一有资格在零时间删除的顶点，并且每个有效过程都必须从其中之一开始。 
3. 维护一个数组来跟踪顶点是否已被删除。 这可以防止双重处理并确保每个顶点在输出顺序中恰好出现一次。 
4. 重复从队列中提取一个顶点v，并检查它是否仍然有效以删除。 如果它已经被删除或者由于之前的更新而导致其当前的程度很奇怪，我们会跳过它。 否则，我们将其删除并将其附加到输出序列中。 
5. 当删除一个顶点 v 时，我们减少了树中它仅存的邻居的度数。 在有根表示中，这通常是其父级和子级仍然存在。 每个度数发生变化的邻居都可能变得偶数，因此如果它尚未被删除并且现在度数为偶数，我们将其添加到队列中。 
6. 继续，直到队列为空。 最后，如果我们删除了所有顶点，我们将输出记录的顺序。 否则，不存在有效序列。 

这种排序足够的原因是每次删除仅影响相邻奇偶校验，并且在树中这些影响不会创建远程依赖关系。 队列确保我们始终在顶点符合条件时准确地处理它们，因此我们永远不会错过可以解锁其他顶点的有效删除。 

### 为什么它有效

 该算法保持了队列中每个顶点当前都是偶数且尚未被删除的不变性。 每次删除只会改变其邻居的程度奇偶性，并且会立即重新考虑这些邻居的资格。 由于该图是非循环的，因此每条边都贡献一个局部依赖性，因此如果存在有效的全局排序，则任何循环依赖性都不会阻止最终处理。 这确保了只要存在有效的完全消除顺序，队列驱动的进程就会发现它而无需回溯。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    adj = [[] for _ in range(n)]
    deg = [0] * n

    for i in range(n):
        if p[i] != 0:
            v = i
            u = p[i] - 1
            adj[v].append(u)
            adj[u].append(v)
            deg[v] += 1
            deg[u] += 1

    removed = [False] * n
    q = deque()

    for i in range(n):
        if deg[i] % 2 == 0:
            q.append(i)
