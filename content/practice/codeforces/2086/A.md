 ## 解决方案
 ## 问题理解

 我们被要求确定需要多少公斤云莓来生产一定数量的果酱罐，因为果酱是由等量的浆果和糖混合制成的，并且在烹饪过程中，总质量的 25% 会蒸发。 输入给出了几个测试用例的罐子数量，输出应该是每个测试用例所需的浆果公斤数。 

简单来说，每罐果酱的最终质量固定为 3 公斤。 为了生产它，我们将等量的浆果和糖混合在一起，总计超过 3 公斤，因为 25% 会蒸发。 从代数上来说，如果我们使用`x`公斤浆果和`x`kg 糖，最终质量为`3x/2`蒸发后。 我们需要每个罐子的重量等于 3 公斤。 解决`3x/2 = 3`给出`x = 2`每罐浆果公斤数。 因此，问题就简化为将罐子的数量乘以 2 以获得所需的浆果。 

限制很温和：最多 10^4 个测试用例，每个测试用例最多 10^8 个 jar。 这立即表明任何解决方案每个测试用例都必须是 O(1)。 迭代或基于模拟的方法是不必要的，而且速度太慢。 边缘情况涉及最少数量的 jar (`n = 1`）和最大可能数（`n = 10^8`），但计算仍然是简单的乘法，不会溢出标准 64 位整数。 

一个幼稚的错误是错误地计算蒸发分数或忘记乘以罐子的数量。 例如，计算`(3 * n) * 0.75`因为浮点数和舍入可能会导致大的误差`n`。 正确的方法是纯整数运算：`2 * n`。 

## 方法

 蛮力方法将尝试通过反复混合浆果和糖并应用 25% 蒸发来模拟制作每个罐子。 为了`n = 10^8`jars，这是完全不切实际的。 从数学上观察这个问题揭示了一个直接的公式：每个罐子正好需要 2 公斤浆果。 一旦确定了这一点，最佳解决方案就是将 jar 数量乘以 2。 

关键的见解是问题是线性的：蒸发因子是恒定的，并且每个罐子都是独立的。 jar 之间不存在依赖性，也不存在收益递减。 这将解决方案从潜在的迭代模拟减少到每个测试用例的一次乘法。 浮点运算是不必要的； 整数运算就足够了。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| 每个测试用例 O(n) | O(1) | O(1) | 对于大 n 来说太慢 |
 | 直接乘法 | 每个测试用例 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，读取 jar 的数量`n`。 
3. 计算所需浆果数量：`2 * n`。 
4. 打印结果。 

为什么这样有效：每个罐子需要 2 公斤浆果，源自配方`final_mass = 3/4 * total_mass`，求解`total_mass / 2 * 2/3 = 1`一罐可产出 2 公斤浆果。 由于每个罐子都是独立的，因此总数是线性的`n`。 整数算术可确保准确的答案，而不会出现舍入错误。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    print(2 * n)
```该解决方案使用快速 I/O`sys.stdin.readline`，尽管对于这个问题的标准`input()`就足够了。 每个测试用例都是独立处理的，乘以 2 就足以说明每个罐子所需的浆果。 

## 工作示例

 | n | 计算| 结果 |
 | ---| ---| ---|
 | 1 | 2 * 1 | 2 |
 | 3 | 2 * 3 | 2 * 3 6 |

 为了`n = 1`，单个罐子需要2公斤浆果。 为了`n = 3`，三罐总共需要6公斤。 迹线证实了公式`2 * n`正确计算每种情况下所需的质量。

 考虑到输入限制，这是最佳的，我们必须阅读`t`测试用例并输出每个结果。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        n = int(input())
        print(2 * n)
    sys.stdout = sys.__stdout__
    return output.getvalue().strip()

# Provided samples
assert run("2\n1\n3\n") == "2\n6", "sample tests"

# Custom cases
assert run("1\n10\n") == "20", "ten jars"
assert run("1\n100000000\n") == "200000000", "max jars"
assert run("3\n1\n2\n5\n") == "2\n4\n10", "multiple small cases"
assert run("1\n0\n") == "0", "zero jars"
```| 测试输入| 预期产出 | 它验证了什么 |
 | ---| ---| ---|
 | 1 | 2 | 最小非零罐子 |
 | 3 | 6 | 少量罐子 |
 | 100000000 | 200000000 | jar 的最大数量，检查大整数处理 |
 | 0 | 0 | 零罐子的边缘情况 |
 | 多个小| 2、4、10 | 多个测试用例|

 ## 边缘情况

 对于`n = 1`，计算`2 * 1 = 2`正确处理罐子的最小正数。 为了`n = 10^8`,`2 * 10^8`在 64 位整数限制内，因此不会发生溢出。 零罐案例`n = 0`产生`0`，正确反映不需要浆果。 这些证实了该公式在整个问题域中都是稳健的。
