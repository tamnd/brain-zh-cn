 ## 解决方案
 ## 问题理解

 类斑马数是一个正整数，其二进制表示形式如下`1`,`101`,`10101`,`1010101`, ...

 换句话说，这些位交替，最低有效位是`1`。 

让$$z_1=1,\quad z_2=5,\quad z_3=21,\quad z_4=85,\dots$$这些正是类似斑马的数字。 

对于正整数$x$，其斑马纹值是其总和为的类斑马纹数的最小个数$x$。 

对于每个查询$[l,r]$和$k$，我们必须计算该区间中有多少个整数具有斑马纹值$k$。 

区间端点可以大到$10^{18}$，因此迭代数字是不可能的。 即使在间隔内单次通过也需要最多$10^{18}$运营。 该解决方案必须在每个查询的大致多对数时间内工作。 

第一个不明显的观察是下面很少有类似斑马的数字$10^{18}$。 他们满足$$z_{i+1}=4z_i+1,$$所以它们呈指数级增长。 里面只能容纳大约三十个人$10^{18}$。 

第二个陷阱是假设斑马纹值可以用普通的硬币找零 DP 来计算。 硬币价值达到$10^{18}$，所以任何 DP 超过总和都是不可能的。 

第三个陷阱是同一数字的不同分解可能使用不同数量的类斑马被加数。 例如，$$21 = z_3$$有斑马值$1$， 虽然$$21 = 5+5+5+5+1$$使用五个加数。 我们必须直接推理最优分解。 

考虑查询```
1 1 1
```答案是`1`因为$1$本身是斑马状的。 任何意外地只计算至少两个斑马数之和的方法都会在这里失败。 

考虑```
2 10 100
```答案是`0`。 虽然$k$可能大到$10^{18}$, 没有最多的数字$10^{18}$任何地方都可以有接近那么大的斑马值。 及早处理此类案件至关重要。 

## 方法

 暴力方法会生成中的每个数字$[l,r]$，计算其斑马线值，并计算匹配数。 

即使我们以某种方式在恒定时间内计算出斑马线值，间隔长度也可以是$10^{18}$。 这是完全不可行的。 

关键是不要再思考数字本身，而是要研究类似斑马的数字的结构。 

让$$z_i=\frac{4^i-1}{3}.$$这些满足$$z_{i+1}=4z_i+1.$$假设最优分解至少包含某些内容的五个副本$z_i$。 

为了$i>1$,$$5z_i=z_{i+1}+4z_{i-1}.$$右侧使用相同数量的被加数。 重复此变换会删除所有大于四的系数。 

结果，每个数都有一个最优分解$$x=\sum c_i z_i,$$和$$0\le c_i\le 4.$$第二次减少来自$$z_{i+1}=4z_i+1.$$如果某个系数$c_i=4$并且它下面有任何正系数，那么我们可以替换$$4z_i+1$$经过$$z_{i+1},$$减少被加数的数量。 因此，在最优分解中，每当一个数字$4$出现时，所有低位数字必须为零。 

这给出了规范的表示：$$x=\sum c_i z_i,$$其中每个数字都在$0$和$4$，第一个数字之后等于$4$，所有低位数字均为零。 

斑马值简单来说就是$$\sum c_i.$$现在问题变成了一个奇怪的数字系统中的数字DP问题。 我们计算不超过界限的表示$N$其数字和等于$k$。 

由于斑马数字只有大约三十个，因此 DP 很小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(r-l+1)$|$O(1)$| 太慢了 |
 | 最佳数字DP |$O(30^2)$每个查询|$O(30^2)$| 已接受 |

 ## 算法演练

 ### 预计算

 1. 生成所有类斑马数$z_i\le 10^{18}$使用$$z_{i+1}=4z_i+1.$$2. 这样的数字大约只有三十个。 

### 将边界转换为斑马数字

 1. 对于给定的$N$，计算其在基础中的贪婪表示$\{z_i\}$。 
2. 从最大到最小处理斑马数。 在每个位置，取可能的最大系数。 
3. 结果数字总是在$0$和$4$。 

复发$z_{i+1}=4z_i+1$保证贪婪分解产生 DP 使用的规范数字系统。 

### 数字DP

 1.让`digits[i]`是系数$z_i$在代表中$N$。 
2. 按照从最重要到最不重要的顺序处理位置。 
3. 维护四个DP参数：

 - 当前位置
 - 我们是否仍然紧张$N$- 当前数字总和
 - 是否为数字$4$已经出现了
 4. 如果是一个数字$4$已经出现了，剩下的每个数字都必须为零。 这强制执行规范表示条件。 
5. 否则，尝试所有数字$0$达到允许的限度。 
6. 将所选数字添加到运行数字总和中。 
7. 最后，count 表示其数字和等于$k$。 

### 范围查询

 1.让$F(N,k)$是整数的个数$x\le N$其斑马线值等于$k$。 
2. 答案为$[l,r]$是$$F(r,k)-F(l-1,k).$$### 为什么它有效

 每个最优分解都可以进行变换，直到所有系数都属于$\{0,1,2,3,4\}$。 任何包含数字的表示形式$4$与正的较低系数一起并不是最佳选择，因为一个副本$z_{i+1}$可以替代$4z_i+1$并减少被加数的数量。 

因此，每个数字都有一个唯一的规范表示，满足：$$0\le c_i\le 4,$$第一个数字之后等于$4$，所有低位数字均为零。 

斑马线值等于这些数字的总和。 数字 DP 精确地枚举了这些规范表示，并统计了那些数字和为$k$。 由于每个有效表示恰好对应于一个整数，反之亦然，因此 DP 返回的计数是正确的。 

## Python 解决方案```python
import sys
from functools import lru_cache

input = sys.stdin.readline

Z = [1]
while True:
    nxt = Z[-1] * 4 + 1
    if nxt > 10**18:
        break
    Z.append(nxt)

M = len(Z)

def count_upto(n, k):
    if n <= 0:
        return 0

    if k > 4 * M:
        return 0

    digits = [0] * M
    rem = n

    for i in range(M - 1, -1, -1):
        digits[i] = rem // Z[i]
        rem %= Z[i]

    @lru_cache(None)
    def dfs(pos, tight, s, locked):
        if s > k:
            return 0

        if pos < 0:
            return 1 if s == k else 0

        if locked:
            d = 0
            if tight and d > digits[pos]:
                return 0
            ntight = tight and (d == digits[pos])
            return dfs(pos - 1, ntight, s, 1)

        limit = digits[pos] if tight else 4

        ans = 0
        for d in range(limit + 1):
            ntight = tight and (d == limit if tight else False)

            if tight:
                ntight = (d == digits[pos])

            ans += dfs(
                pos - 1,
                ntight,
                s + d,
                locked or (d == 4)
            )

        return ans

    return dfs(M - 1, 1, 0, 0)

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        l, r, k = map(int, input().split())

        if k > 4 * M:
            out.append("0")
            continue

        ans = count_upto(r, k) - count_upto(l - 1, k)
        out.append(str(ans))

    sys.stdout.write("\n".join(out))

solve()
```第一部分构建所有类似斑马的数字$10^{18}$。 仅存在大约三十个值，这就是为什么后来的 DP 仍然很小。 

功能`count_upto`计算$F(N,k)$。 它首先转换$N$进入其贪婪的斑马数字表示形式。 这些数字的作用与标准数字 DP 中十进制数字的作用相同。 

状态变量`locked`是微妙的部分。 一次是一个数字`4`出现时，所有剩余的低位数字必须为零。 忘记此限制会计算非最佳表示并产生不正确的斑马值。 

修剪条件`s > k`保持状态空间较小。 由于最大可能的数字和仅约为$120$，DP 仍然非常快。 

最后，使用标准前缀计数技术回答每个查询：$$[l,r] = [1,r] - [1,l-1].$$## 工作示例

 ### 示例 1

 输入：```
1 100 3
```涉及的斑马线编号为：$$1,\;5,\;21,\;85.$$贪婪斑马表示$100$是：

 | 斑马号| 系数|
 | ---| ---|
 | 85 | 85 1 |
 | 21 | 21 0 |
 | 5 | 3 |
 | 1 | 0 |

 所以$100 = 1\cdot85 + 0\cdot21 + 3\cdot5 + 0\cdot1$。 

DP 探索所有不超过这些数字的规范表示，并计算那些具有数字和的数字$3$。 

结果是：```
13
```这个例子表明斑马纹值完全由规范表示的数字和决定。 

### 示例 2

 输入：```
15 77 2
```相关斑马号码：$$1,\;5,\;21.$$斑马线值区间内的数字$2$是：$$26=21+5,$$

$$42=21+21,$$

$$50=5+45? \text{ not canonical},$$DP自动过滤无效分解。 

最终计数为：```
3
```这个例子说明了为什么计算任意总和是不够的。 只有规范的最优分解才重要。

 ## 边缘情况

 考虑```
1
1 1 1
```贪婪的斑马表示只是以下的一份副本$z_1=1$。 数字和是$1$，所以 DP 对其进行计数。 输出是`1`。 

考虑```
1
2 10 100
```斑马数字只有大约三十个。 每个规范数字最多为四，因此最大斑马值如下$10^{18}$至多是$120$。 自从$100$已经超出了许多间隔的可实现范围，并且$10^{18}$是全局极限时，DP 立即返回零状态。 输出是`0`。 

考虑```
1
21 21 1
```规范的表示是$$21 = z_3.$$其位数和为$1$，所以它的斑马值为$1$。 DP 正好达到一个接受状态并返回`1`。 

最微妙的情况是当一个数字$4$出现。 假设一个表示尝试使用$$4z_i + z_j$$和$j<i$。 自从$$z_{i+1}=4z_i+1,$$这种表示并不是最佳的。 这`locked`国家通过强制所有较低数字在数字后变为零来禁止此类配置$4$被选中。 这正是规范最优分解所需的条件。
