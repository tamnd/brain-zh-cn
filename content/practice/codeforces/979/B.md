 ## 解决方案
 ## 问题理解

 我们得到三根等长的绳子，每根绳子代表三名玩家之一拥有的一条丝带。 玩家只需一步即可将字符串中的一个字符更改为任何其他字母。 它们都获得相同的移动次数，目标是在所有修改后最大化字符串的“美感”量。 

字符串的美感被定义为其中任何连续子字符串出现的最大次数。 例如，如果一个字符串完全由相同的字符组成，则单字符子串出现在每个位置，因此它出现的次数等于字符串的长度，这也是它的美妙之处。 

关键的观察是，这个游戏完全是关于每个字符串可以如何接近地转换为统一字符串，因为统一字符串最大化重复的子字符串。 

输入由一个整数 n（每个玩家允许的单字符更改数量）组成，后跟三个字符串。 我们必须确定哪位玩家在每步恰好 n 步后能够达到尽可能最高的最终美感。 

约束很重要：n 可以大到 10^9，而每个字符串长度最多为 10^5。 这立即意味着我们无法逐步模拟转换。 任何解决方案都必须仅依赖于对字符串的不匹配或结构属性进行计数。 

当 n 与字符串长度相比非常大时，会出现微妙的边缘情况。 在这种情况下，玩家可以自由地覆盖每个字符，有可能使所有字符串都相同。 例如，如果一个字符串的长度为5，n为10，则玩家可以将所有位置更改为同一个字符，使最终的美度等于5。 

另一个重要的情况是当 n 很小时。 那么只能进行部分更改，并且最佳策略受到可以将多少个字符转换为所选目标字母的限制。 

一种简单的方法可能会尝试在每次修改后模拟更改或探索子串结构，但由于时间限制和可能转换的指数数量，这会失败。 

## 方法

 核心的简化是认识到可实现的最佳美感始终来自于使琴弦尽可能均匀。 

如果一个字符串完全由一个字符（例如“a”）组成，则由“a”组成的每个子字符串都会最大程度地重复。 事实上，美感正是字符串的长度，因为每个位置都会导致同一子带的重复出现。 

因此，真正的问题是：最多使用 n 个更改可以将多少个字符转换为单个重复字符？ 

对于任何固定目标字符，将字符串转换为所有该字符的成本是尚未等于该字符的位置数。 如果我们选择最好的目标角色，我们就能最小化这种成本。 如果最小成本至多为n，那么整个字符串就可以变得均匀，达到与全长相等的美感。 

如果没有足够的操作来完全同质化字符串，那么最好的策略是最大化单个字符的频率。 每次更改都可以将一个不匹配字符转换为主导字符，因此最终最大频率变为初始最大频率加上 n，上限为字符串长度。 

这为每个玩家提供了一个非常清晰的公式：

 我们计算原始字符串中任何字符的最大频率，然后添加 n，但不要超过字符串的长度。 

这是最优的，因为每个操作最多可以将一个选定字符的计数增加 1，并且在多个字符之间分摊工作没有任何好处。 

最后，我们比较三个字符串的结果值并选出获胜者。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 编辑和子串的暴力模拟| 指数| 高| 太慢了|
 | 计算频率并应用贪婪最大化 | O(L) | O(1) 额外 | 已接受 |

 ## 算法演练

 1. 对于每个字符串，计算每个字符的频率。 

这捕获了有多少位置已经与潜在的目标字母匹配。 
2. 识别字符串中的最大频率值。 

如果我们选择最常见的角色作为目标，这代表了最好的起点。 
3. 计算 n 次操作后可达到的最大频率：

 min（字符串长度，最大频率 + n）。 

每一次操作可以将一个非目标字符转换为目标字符，计数加一。 
4. 对所有三名玩家重复相同的计算。 
5. 比较结果值并确定最高值。 
6. 如果一名玩家的价值严格更大，则该玩家获胜； 否则，结果为平局。 

添加 n 背后的推理步骤是，每次移动都可以将所选统一块的大小恰好增加 1，直到整个字符串变得统一。 

### 为什么它有效

 不变的是，在 k 次操作之后，任何选定的字符最多可以出现original_count + k 次，因为每次操作只能将一个不匹配的位置翻转到该字符中。 没有任何操作可以同时增加两个位置或同时使多个角色受益。 因此，最佳策略始终是致力于单个角色并最大化其频率。 由于任何达到最大频率的排列都对应于最大化重复子串，这直接决定了美观。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    t = input().strip()
    u = input().strip()

    def best(s):
        freq = [0] * 128
        for ch in s:
            freq[ord(ch)] += 1
        mx = max(freq)
        return min(len(s), mx + n)

    ks = best(s)
    sh = best(t)
    kt = best(u)

    res = max(ks, sh, kt)

    cnt = 0
    if ks == res:
        cnt += 1
    if sh == res:
        cnt += 1
    if kt == res:
        cnt += 1

    if cnt > 1:
        print("Draw")
    elif ks == res:
        print("Kuro")
    elif sh == res:
        print("Shiro")
    else:
        print("Katie")

if __name__ == "__main__":
    solve()
```该解决方案对每个字符串计算一次字符频率，并评估在 n 次操作下单个字符可实现的最佳优势。 长度最小值确保我们不会超过完全均质化。 

比较逻辑明确地跟踪关系以确定多个玩家是否达到相同的最大值。

 ## 边缘情况

 一种边缘情况是所有三个字符串都相同。 在这种情况下，每个玩家都有相同的最大频率，等于全长，并且由于上限，添加 n 没有任何作用。 该算法产生相同的结果并正确地宣布平局。 

另一种边缘情况是 n 为零时。 结果完全取决于初始最大字符频率，因此解决方案简化为纯频率比较，无需任何变换组件。 

当 n 超过所选字符的不匹配数时，会出现第三种情况。 例如，在像“abac”这样的字符串中，如果我们选择“a”，则只需要两次操作即可使其完全统一。 任何额外的操作都不能改进超过全长，并且公式中的上限可以防止过度计数。
