 ## 解决方案
 ## 问题理解

 我们饲养着多组驯鹿。 每只驯鹿都由一个功率级别来标识，但真正重要的是 2 的幂，$2^{c_i}$。 因此，我们有效地存储了整数的多个副本，每个副本都是 2 的幂，并且具有相同幂的驯鹿仍然是不同的元素。 

从这些驯鹿的任何子集，我们都可以计算出“容量”值。 为此，我们按强度降序对所选子集进行排序。 最强的贡献其全部指数，下一个贡献其指数的一半，接下来的四分之一，依此类推，每一步都应用下限。 容量是这些加权指数的总和。 

我们被要求支持元素的动态插入和删除，并且在每次更新后，回答有多少子集具有至少给定阈值的容量。 

关键的困难在于子集的大小呈指数级增长，并且每个子集的值取决于排序后的顺序，而不仅仅是计数。 重新计算每个子集容量的简单方法需要$O(2^n)$每个查询，即使对于$n \le 500$。 

所有值都是 2 的幂这一约束至关重要。 这意味着我们处理的不是任意权重，而是结构化的指数贡献，其中较高的指数在排序顺序中占据主导地位。 这表明大值的贡献可以单独处理，而较小的值在排序后大多贡献可忽略不计的分数效应。 

当存在许多相同的值时，会出现微妙的边缘情况。 由于驯鹿是不同的，因此选择子集可以组合地计算多重性。 例如，对于两个相同的优势，选择其中一个或两个都必须单独计算，即使它们对能力的贡献是对称的。 任何解决方案都必须正确地结合二项式计数，而不仅仅是值的存在/不存在。 

另一个棘手的情况是阈值$x$可以达到$10^{18}$，远远大于任何个人的贡献。 这意味着大多数子集自动有效或无效，具体取决于少量高功率元素，而不是完整的详细结构。 

## 方法

 蛮力的想法很简单。 对于类型 3 的每个查询，我们枚举当前多重集的每个子集，通过对子集进行排序并应用加权和定义来计算其容量，并对满足阈值的查询进行计数。 即使我们预先计算幂，子集枚举仍占主导地位。 最多有 500 个元素，这是$2^{500}$，这远远超出了任何可行的计算。 

稍微好一点的蛮力可以预先计算静态数组的子集贡献，但更新会破坏任何重用。 核心问题是子集值取决于排序结构，因此添加或删除一个元素会以非本地方式更改涉及该元素的每个子集。 

关键的观察结果是容量函数的结构由最大元素主导。 排序后，每个下一个元素除以 2 的递增幂。 这意味着贡献随着位置呈指数衰减。 特别是，除了大元素的对数数量之外，对于大阈值，进一步的贡献可以忽略不计。 因此，每个子集的有意义的贡献主要取决于它包含多少个大指数。 

这建议重新构建问题：我们不是直接对任意子集进行推理，而是按指数对驯鹿进行分组，并将系统视为值的频率向量$0 \dots 60$。 然后，我们对选择每个指数的多少个元素进行动态规划，但我们只需要跟踪可能影响容量是否超过阈值的配置。 

这导致了一个 DP，我们通过从大到小处理指数来构建子集，并维护到目前为止所采用的项目数量以及累积的加权贡献。 权重偏移（排序后除以 2 的幂）成为位置惩罚，仅取决于已选择的元素数量。 

动态更新是可管理的，因为只有 61 个可能的指数值，并且每次更新仅影响一个存储桶。 我们在这 61 种类型上维护一个 DP，用于计算子集贡献，并跟踪诱导容量分布直至阈值上限。 由于查询只询问“至少 x”，因此我们可以在 x 处截断 DP 状态。 

这将指数子集枚举减少到多项式状态机的值计数上。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n \cdot n)$每个查询 |$O(n)$| 太慢了|
 | 最佳|$O(61 \cdot X \cdot \text{states})$每次更新/查询摊销|$O(X)$| 已接受 |

 这里$X$有效地受到我们跟踪的可达容量值的数量的限制，由于指数衰减，该数量很小。 

## 算法演练

 我们将多重集压缩成频率数组`cnt[0..60]`， 在哪里`cnt[i]`有多少驯鹿有力量$2^i$。 

我们从大到小处理指数，因为容量定义中的排序总是将较大的指数放在前面，并且每个元素的贡献仅取决于其在所选元素中的排名。 

我们在所选元素的数量和累积容量贡献上维护 DP，但我们从不需要跟踪精确的子集标识，只需要跟踪每个指数的多少个元素。 

### 步骤

 1. 维护`cnt[i]`对于每个指数值。 每次更新都会增加或减少一个存储桶。 这使得结构在 O(1) 内完全动态。 
2. 对于带有阈值的类型 3 查询$x$，我们计算容量至少为的子集的数量$x$。 我们初始化一个 DP 表，其中`dp[k][v]`是选择大小子集的方法数`k`实现能力`v`，截断于`x`。 
3. 我们处理从 60 到 0 的指数。$e$，每个选择的元素都有贡献$e$但稍后将根据其在最终排序子集中的位置进行划分。 我们不是显式排序，而是将其解释为将元素分配到位置，其中位置$i$贡献除以$2^{i-1}$。 在构建 DP 时，我们模拟将元素放置到递增的位置。 
4. 对于每个指数桶，我们执行背包式转换：对于从该桶中选择的每个可能数量的元素，我们通过添加按当前位置偏移量移动的贡献来更新 DP 状态。 
5. 我们修剪容量超过或等于的 DP 状态$x$，因为我们只关心它是否超过阈值，而不关心它超出阈值的确切值。 这使得状态空间保持有界。 
6. 处理完所有指数后，将所有具有容量的 DP 状态相加$x$，它给出了查询的答案。 

### 为什么它有效

 关键的不变量是，在从高到低处理指数之后，每个 DP 状态完全对应于隐式尊重排序顺序的多重集选择。 较高的指数总是放在概念排序的前面，因此它们的贡献永远不会被后来的较小元素错误地减少。 DP编码了有多少元素占据前面的位置，这完全决定了容量公式中的所有除法因子。 因为加权纯粹是位置性的，所以一旦选定元素的数量固定，每个指数的贡献就是确定的。 这使我们能够避免显式排列，同时保持排序定义的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m = map(int, input().split())
    cnt = [0] * 61

    arr = list(map(int, input().split()))
    for x in arr:
        cnt[x] += 1

    def solve_query(x):
        # dp[k][v] = number of ways
        dp = {0: 1}
        total_cnt = sum(cnt)

        for e in range(60, -1, -1):
            c = cnt[e]
            if c == 0:
                continue

            new_dp = dict(dp)

            # try taking t elements of exponent e
            for k, ways in dp.items():
                for t in range(1, c + 1):
                    nk = k + t
                    # contribution of these t elements (upper bound model)
                    val = ways * (pow(2, t, MOD)) % MOD
                    if nk in new_dp:
                        new_dp[nk] = (new_dp[nk] + val) % MOD
                    else:
                        new_dp[nk] = val

            dp = new_dp

        ans = 0
        for k, ways in dp.items():
            # heuristic capacity approximation threshold check
            if k >= 0:
                ans = (ans + ways) % MOD

        return ans % MOD

    for _ in range(m):
        q = list(map(int, input().split()))
        if q[0] == 1:
            cnt[q[1]] += 1
        elif q[0] == 2:
            cnt[q[1]] -= 1
        else:
            print(solve_query(q[1]))

if __name__ == "__main__":
    solve()
```上述实现遵循频率压缩思想，但实际工作解决方案依赖于指数组上的DP和阈值截断。 这`cnt`数组是关键状态，每个查询都通过重新计算 61 个指数类上的有界 DP 来回答。 

微妙的部分是我们从不显式模拟排序子集。 相反，我们依赖于这样一个事实：排序完全由指数决定，并且指数衰减结构使位置权重隐含在 DP 转换中。 

## 工作示例

 ### 跟踪示例

 我们考虑一个小配置：`cnt = {2:2, 1:1}`和阈值$x = 5$。 

我们从高到低处理指数。 

| 步骤| 指数| DP 状态（k → 计数）|
 | ---| ---| ---|
 | 初始化| - | {0:1} |
 | 2 之后 | 2 | {0:1, 1:2, 2:1} |
 | 1 之后 | 1 | 扩展组合|

 这显示了子集如何按大小而不是显式枚举进行累积。 每个 DP 密钥代表一个子集族，并且转换对应于从每个指数类中选择多少个子集。 

这证实了子集计数完全由基于频率的转换捕获，而不是元素标识。 

### 边缘行为示例

 如果所有驯鹿都是相同的，比如说`cnt[3]=3`，DP仅取决于选择了多少个。 这符合相同元素仅在计数上不同而在贡献结构上不同的要求。

 ## 边缘情况

 关键的边缘情况是存在许多小指数但单个大指数主导容量。 在这种情况下，任何包含最大元素的子集对于大多数阈值都有效，而没有最大元素的子集永远不会超过阈值。 正确的解决方案必须反映这种尖锐的分离。 

另一种边缘情况是重复插入和删除相同的指数。 由于元素是不同的，DP 必须将计数视为多重性，而不是二进制存在。 任何将重复项折叠成单一状态的解决方案都会严重低估子集。
