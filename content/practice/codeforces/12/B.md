 ## 解决方案
 ## 问题理解

 Alice 给 Bob 一个十进制数，并要求他重新排列其数字，以使结果数字尽可能小，同时仍然是不带前导零的有效十进制数。 鲍勃返回另一个数字，我们必须确定他的答案是否实际上是最小的可能排列。 

任务不是生成所有重新排列。 我们只需要检查鲍勃的号码是否符合正确的最小排列即可。 

数字最多为$10^9$，因此它们最多包含 10 位数字。 尽管输入大小很小，但问题仍然需要仔细处理前导零。 一个简单的数字排序就像`"0013"`会产生无效的表示，因为十进制数不能以零开头，除非整个数字本身为零。 

当原始数字包含零时，会出现最危险的边缘情况。 例如：

 输入：```
1002
1002
```正确的最小重排是`1002`， 不是`0012`。 简单地对所有数字升序排序的粗心实现将错误地构建`"0012"`。 

另一个棘手的情况是数字本身为零时。 

输入：```
0
0
```答案是有效的，因为唯一的重排仍然为零。 

当候选答案具有正确的数字但不是最小的时，就会发生另一种错误。 

输入：```
310
130
```数字匹配，但最小的有效排列是`103`，所以正确的输出是`WRONG_ANSWER`。 

核心困难不在于检查数字是否匹配。 真正的挑战是在“无前导零”限制下构建字典顺序上最小的有效排列。 

## 方法

 暴力方法是生成原始数字的每个数字排列，丢弃那些带有前导零的排列，将剩余的排列转换为数字，并取最小值。 然后我们将这个最小值与鲍勃的答案进行比较。 

这是有效的，因为它直接遵循问题的定义。 检查每一种可能的重新排列，因此保证找到最小的有效重新排列。 

问题在于排列是阶乘增长的。 一个 10 位数字最多有$10! = 3,628,800$排列。 这已经是数百万候选者，如果我们想避免重复工作，重复的数字会增加簿记的复杂性。 对于如此小的输入大小，它可能仍然可以在某些语言中通过，但是对于具有简单的建设性解决方案的问题来说，它不必要地昂贵。 

关键的观察是最小的有效数字应该将最小的非零数字放在前面，因为第一位数字对数字的值影响最大。 固定第一个数字后，每个剩余位置应包含最小的可用数字，包括零。 

这立即暗示了一个贪婪的构造：

 首先，将所有数字升序排序。 

如果第一位数字不为零，则排序顺序已经是最佳的。 

如果排序顺序以零开头，则找到第一个非零数字，将其放在前面，然后按升序附加所有剩余数字。 

例如：`3100`排序后的数字：`0013`第一个非零数字是`1`。 

将其移到前面：`1003`这是最小的有效安排。 

构建了这个规范的最小形式后，我们只需将其与鲍勃的答案进行比较。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(d! \cdot d)$|$O(d)$| 太慢/不必要|
 | 最佳 |$O(d \log d)$|$O(d)$| 已接受 |

 这里，$d$是位数。 

## 算法演练

 1.读取原数`n`作为字符串和鲍勃的答案`m`作为字符串。 

将它们视为字符串可以避免处理过程中出现前导零问题。 
2. 转换数字`n`放入列表中并按升序对它们进行排序。 

这给出了字典顺序上最小的数字排列。 
3. 检查排序后第一位是否为零。 

如果不为零，则排序顺序已经是最小的有效数字。 
4. 如果第一个数字为零，则从左到右扫描，直到找到第一个非零数字。 

该数字必须成为前导数字，因为任何有效数字都必须以非零数字开头。 
5. 将第一个非零数字交换到前面的位置。 

所有剩余的数字都保持排序，因此结果数字仍然很小。 
6. 将数字连接成代表最小有效重排的字符串。 
7. 将构建的结果与 Bob 的答案进行比较。 

如果它们完全匹配，则打印`OK`。 否则打印`WRONG_ANSWER`。 

### 为什么它有效

 该算法依赖于位置值。 最左边的数字对数字大小的贡献最大，因此最小化它始终是最高优先级。 

在所有非零数字中，为第一个位置选择最小的数字会给出尽可能小的主导贡献。 固定该数字后，应独立最小化剩余位置，这是通过对剩余数字升序排序来实现的。 

因为第一个数字之后的每个数字都以尽可能小的顺序放置，所以没有其他有效的重新排列可以产生更小的数字。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = input().strip()
    m = input().strip()

    digits = sorted(n)

    if digits[0] == '0':
        for i in range(len(digits)):
            if digits[i] != '0':
                digits[0], digits[i] = digits[i], digits[0]
                break

    smallest = ''.join(digits)

    if smallest == m:
        print("OK")
    else:
        print("WRONG_ANSWER")

solve()
```解决方案首先将两个数字读取为字符串。 这很重要，因为鲍勃的答案可能在输入中包含前导零，并且立即转换为整数会丢失该信息。 

的数字为`n`按升序排序。 如果第一个数字已经非零，则排序序列立即是最小的有效排列。 

当排序序列以零开头时，代码会搜索第一个非零数字并将其交换到第一个位置。 此操作就足够了，因为剩余的数字已经按升序排序。 不需要额外的重新安排。 

最终的比较是作为字符串比较来执行的。 这比数字比较更安全，因为`"0012"`和`"12"`代表该问题上下文中的不同答案。

import sys
import io

def solve():
    input = sys.stdin.readline

    n = input().strip()
    m = input().strip()

    digits = sorted(n)

    if digits[0] == '0':
        for i in range(len(digits)):
            if digits[i] != '0':
                digits[0], digits[i] = digits[i], digits[0]
                break

    smallest = ''.join(digits)

    if smallest == m:
        print("OK")
    else:
        print("WRONG_ANSWER")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output.strip()

# provided sample
assert run("3310\n1033\n") == "OK", "sample 1"

# minimum value
assert run("0\n0\n") == "OK", "single zero"

# leading zero trap

# maximum size boundary
assert run("1000000000\n1000000000\n") == "OK", "10 digits with many zeroes"

 考虑输入：```

1002
```排序后的数字变为：```

```这种排列是无效的，因为它从零开始。 该算法扫描第一个非零数字，即`1`，并将其交换到前面：```
1002
```剩余的数字保持排序，因此这是最小的有效排列。 

现在考虑：```
0
0
```数字列表仅包含一个字符：```
['0']
```不需要交换，因为没有非零数字。 构建的结果仍然是`"0"`，这与正确答案相匹配。 

最后，考虑：```
909
