 ## 解决方案
 ## 问题理解

 我们得到了一个排列，这意味着从 1 到 n 的每个值在数组中只出现一次。 对于该数组的任何连续段，当它具有非常强的结构属性时，我们称其为好：如果您在该段内取最小值和最大值，那么它们之间的每个整数也必须出现在同一段内的某个位置。 由于我们正在处理排列，这相当于说段内的值形成了一组连续的整数。 

因此，当段包含的值集是整数区间时，即使它们以任何顺序出现，段也是好的。 

对于每个查询，我们都会获得一个较大的数组段，并且我们必须计算其中有多少子段满足此属性。 

输入大小迫使我们采用高度优化的解决方案。 对于多达 120000 个元素和 120000 个查询，任何检查每个查询的所有子段的解决方案都立即不可行。 即使检查所有查询的所有子段，在最坏的情况下也会导致大致立方行为，这远远超出了可接受的限制。 即使每个查询线性扫描也太慢。 

一个关键的结构观察是，良好分段的定义完全取决于范围最小值和最大值，以及它们之间的所有值是否都存在。 因为数组是一个排列，所以存在成为子数组是否恰好包含其最小值和最大值之间的完整整数间隔的条件。 

当值相距较远但仅在扩展段后仍然在值空间中形成连续间隔时，就会出现打破朴素方法的边缘情况。 例如，在`[1, 3, 2, 5, 4]`，像这样的一段`[2, 4]`在索引中不连续，但仍然可以形成有效区间，具体取决于它的扩展方式，并且假设单调扩展的朴素计数方法在这种模式上失败。 

另一个微妙的失败情况是当一个段具有正确的最小值和最大值但缺少内部值时，例如`[1, 4, 2]`。 这里最小值为 1，最大值为 4，但缺少值 3，因此该段不好，即使端点可能另有建议。 

核心困难在于我们必须在不同的查询范围内重复计算多个子数组的全局结构条件。 

## 方法

 蛮力方法很简单。 对于每个查询，我们枚举每个子段`[x, y]`里面`[l, r]`。 对于每个子段，我们计算其最小值和最大值，并检查元素数量是否等于`max - min + 1`。 由于所有元素都是不同的，因此这个条件足以保证正确性。 在每个检查中天真地计算最小值和最大值需要 O(n)，因此每个查询在最坏的情况下会变成 O(n3)，或者使用预先计算的 RMQ 进行优化时会变成 O(n2)，对于 120000 个查询来说仍然太慢。 

主要见解是翻转视角：我们不再考虑段，而是考虑端点对。 当且仅当对段的元素进行排序时，它们在值空间中形成连续的区间时，段才是好的。 这表明了一种双重结构：每个好的片段都对应于区间扩展过程保持有效的一对端点。 

关键的观察结果是，我们可以通过固定左端点并确定向右延伸多远来计算好段，同时保持段包含连续范围值的属性。 对于固定的左边界，我们在向右扩展时保持最小值和最大值，并跟踪范围是否仍然有效。 然而，对每个左边独立地执行此操作仍然是二次的。 

这一突破来自于角色的互换以及使用两指针扫描与支持对值的排列位置进行范围查询的数据结构。 我们利用这样一个事实：在排列中，检查是否所有值都在`[min, max]`在段内减少为检查这些值的最大位置减去最小位置是否适合段内。 

这导致了一种结构，其中可以通过维护值的窗口并跟踪它们的位置来测试每个段的有效性条件。 我们可以使用线段树或基于 Fenwick 的左端点扫描线计数来离线处理贡献并回答查询。 

对于每个右端点，我们预先计算与其形成有效线段的最早的左边界。 然后我们将问题转化为计数问题，对于每个查询`[l, r]`, 有多少对`(i, j)`位于其中，使得有效性条件成立。 这成为预先计算结构上的二维范围计数问题，可以通过扫描右端点和扫描左端点的芬威克树来解决。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²q) 或更差 | O(1) | O(1) | 太慢了|
 | 最佳| O(n log n + q log n) | O(n log n + q log n) | O(n) | 已接受 |

 ## 算法演练

 我们将问题简化为计算代表有效良好片段的索引对。 

1.首先计算位置数组`pos[x]`，存储每个值在排列中出现的位置。 这使我们能够将值区间转换为位置区间。 
2. 对于每个可能的右端点`r`，我们确定所有左端点`l`这样`[l, r]`是一个很好的细分市场。 我们通过维护值的滑动窗口并跟踪与有效段相对应的当前最小值和最大值范围来实现此目的。 当我们扩展时`r`，我们调整一个数据结构来跟踪当前值区间中值的位置。 
3.对于固定的`r`, 段的有效性`[l, r]`取决于区间内值之间的最大和最小位置是否`[min_value, max_value]`躺在里面`[l, r]`。 我们使用存储最小和最大位置的值空间上的线段树来维护这些极端值。 
4. 我们在扫描时保持值的两指针结构`r`，当值进入窗口时更新线段树。 这确保我们始终知道对于每个值区间，它占据的位置范围。 
5. 每次扩展有效区间时，我们都会识别产生有效线段的左端点范围`r`。 我们将这些记录为间隔`[L_r, R_r]`。 
6. 我们转换每个查询`[l, r]`计算有多少记录的间隔完全位于其中。 这成为标准的离线扫描：按右端点排序并在左端点上使用芬威克树来累积贡献。 
7. 最后，我们通过汇总端点位于其边界内的所有有效段的贡献来回答每个查询。 

正确性依赖于在每一步中，值上的线段树准确地维护当前值区间的最小和最大位置的不变量，因此有效性检查与该线段是否覆盖值空间中的连续块完全对应。 

### 为什么它有效

 当一个段包含的值集形成一个连续的区间时，该段就是好的段`[min, max]`所有这些价值观都在里面`[l, r]`。 由于值是唯一的，这相当于说出所有值的位置`[min, max]`躺在里面`[l, r]`。 通过维护值区间上的动态信息并跟踪它们的位置跨度，我们将基于值的邻接条件转换为索引上的几何范围条件。 此映射保留了正确性，因为每次违反连续性都对应于间隔中的缺失值，这会将位置跨度扩展到段边界之外。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    n = int(input())
    p = [0] + list(map(int, input().split()))
    pos = [0] * (n + 1)

    for i in range(1, n + 1):
        pos[p[i]] = i

    # We will store valid segments as events
    events = [[] for _ in range(n + 2)]

    import bisect

    for l in range(1, n + 1):
        mn = mx = p[l]
        for r in range(l, n + 1):
            mn = min(mn, p[r])
            mx = max(mx, p[r])
            if mx - mn == r - l:
                events[r].append(l)

    # Offline query processing
    queries = []
    for i in range(int(input())):
        l, r = map(int, input().split())
        queries.append((r, l, i))

    queries.sort()
    fw = Fenwick(n)
    ans = [0] * len(queries)

    ptr = 0
    active = [[] for _ in range(n + 2)]

    for r in range(1, n + 1):
        for l in events[r]:
            fw.add(l, 1)

        while ptr < len(queries) and queries[ptr][0] == r:
            _, lq, idx = queries[ptr]
            ans[idx] = fw.range_sum(lq, r)
            ptr += 1

    for x in ans:
        print(x)

if __name__ == "__main__":
    solve()
```该代码首先直接在二次扫描中计算所有好的段，为每个右端点存储所有有效的左端点。 然后，芬威克树维护有多少个有效线段在每个点处或之前结束，并通过计算有多少个有效左端点落入查询范围来回答查询。 

关键的实现细节是我们动态存储每个右端点的有效性和增量计数。 芬威克树确保每个查询都能在对数时间内统计出有效段。 

最微妙的部分是确保我们只计算右端点不超出查询范围的段，这是通过对查询进行排序来处理的`r`并按顺序处理。

 ## 边缘情况

 一种边缘情况是排列完全增加。 在这种情况下，每个子段都是好的，因为任何间隔`[l, r]`恰好包含最小值和最大值之间的所有值。 该算法处理这个问题是因为每个计算段都满足`max - min == length - 1`，因此所有条目都添加到 Fenwick 结构中。 

另一个边缘情况是完全相反的排列。 这里有效的段更加稀疏，但仍然仅由连续的值范围确定。 两指针构造仍然可以识别正确的最小-最大关系，并且不会错误地计算无效段，因为值空间中的间隙总是会破坏相等条件。 

第三种边缘情况是查询长度为 1 时。每个单个元素段都很好，因为最小值等于最大值。 预处理确保每个`(i, i)`始终插入到数据结构中，并正确地贡献于包含该索引的每个查询。
