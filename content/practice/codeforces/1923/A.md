[CF 1923A - 移动芯片](https://codeforces.com/problemset/problem/1923/A)

 **求解时间：** 1m 52s

 ## 解决方案
 ## 问题理解

 我们有一排单元格，每个单元格要么包含一个芯片，要么是空的。 目标是通过重复拾取一个筹码并将其移动到其左侧最近的空单元中，将筹码向左移动到连续的组中。 任务是确定使所有筹码形成一个不间断的块所需的最小移动次数。 

输入提供多个测试用例。 每个测试用例都有多个单元格`n`（2 到 50 之间）和一个描述哪些单元包含芯片的数组。 每个测试用例的输出是一个整数，表示所需的最少移动次数。 

因为`n`最多 50，任何对数组进行几次简单扫描的算法都将高效运行。 和`t`最多 1000 个测试用例，以线性时间处理每个数组的解决方案是可以接受的。 

这个问题有微妙的边缘情况。 例如，如果所有筹码已经连续，则不需要移动。 如果有一个筹码的左侧有空单元格，则无需移动。 计算每个空单元格或尝试盲目模拟移动的幼稚实现可能会过度计数，因为只有**最左边和最右边芯片**之间的空单元格才重要。 例如，`[0, 1, 0, 1, 0, 1, 0]`有 3 个筹码和 3 个间隙，但只需要关闭第一个筹码和最后一个筹码之间的两个间隙，因此只需要 2 次移动。 

## 方法

 暴力方法是明确地模拟该过程：重复拾取芯片并将其向左移动，直到形成连续的块。 虽然这是正确的，但这是不必要的，因为我们只关心最小的移动次数，而不是确切的顺序。 即使对于小型阵列，模拟每一步的效率也很低，并且存在出现相差一错误的风险。 

关键的观察结果是，只有**第一个筹码和最后一个筹码**之间的空单元格才有助于移动。 最左侧芯片左侧或最右侧芯片右侧的任何空单元格永远不需要填充，因为没有芯片会移入其中。 因此，最小移动次数就是第一个筹码和最后一个筹码之间的零的数量。 

这将问题简化为扫描一次数组以查找第一个和最后一个码片的索引，然后计算该子数组中的零。 该解决方案是线性的，实施起来极其简单，并且避免了简单模拟的陷阱。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| 每个测试用例的 O(n²) | O(n) | 矫枉过正/不必要|
 | 计算第一个和最后一个芯片之间的零 | 每个测试用例 O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 
2. 对于每个测试用例，请阅读`n`和数组`a`。 
3. 从左到右扫描识别最左边的芯片。 将其索引存储为`first`。 
4. 从右向左扫描，识别最右边的芯片。 将其索引存储为`last`。 
5. 初始化计数器`moves`为零。 
6. 迭代自`first`到`last`。 对于每个单元格，如果它是空的（`0`), 增量`moves`。 
7. 扫描后，`moves`现在拥有所需的最少操作数。 打印出来。 

为什么有效：向左移动任何芯片都可以恰好填满一个空单元格。 由于所有移动都是独立的，并且第一个和最后一个筹码之间只有零很重要，因此对它们进行计数可以得出最小的移动数。 没有任何移动可以进一步减少此计数，并且不需要任何超出此范围的移动。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    first = a.index(1)  # leftmost chip
    last = len(a) - 1 - a[::-1].index(1)  # rightmost chip
    
    moves = 0
    for i in range(first, last + 1):
        if a[i] == 0:
            moves += 1
    print(moves)
```该解决方案使用`list.index`定位第一个芯片，反向扫描定位最后一个芯片。 这些索引之间的迭代对所有空单元格进行计数，这直接对应于所需的移动次数。 没有创建额外的数组，每个测试用例的所有操作都是 O(n)。 反转数组以查找最后一个索引是安全的，因为`n <= 50`。 

## 工作示例

 输入示例：`[0, 1, 1, 1, 0, 1, 1, 0]`| 我| 一个[我] | 移动|
 | --- | --- | --- |
 | 1 | 1 | 0 |
 | 2 | 1 | 0 |
 | 3 | 1 | 0 |
 | 4 | 0 | 1 |
 | 5 | 1 | 1 |
 | 6 | 1 | 1 |

 解释：第一个码片位于索引 1 处，最后一个码片位于索引 6 处。它们之间恰好有一个零（索引 4），因此`moves = 1`。 

另一个例子：`[1, 0, 1, 0, 1]`| 我| 一个[我] | 移动|
 | --- | --- | --- |
 | 0 | 1 | 0 |
 | 1 | 0 | 1 |
 | 2 | 1 | 1 |
 | 3 | 0 | 2 |
 | 4 | 1 | 2 |

 解释：第一个筹码在 0 处，最后一个筹码在 4 处。位置 1 和 3 处都有零。两者都需要填充，因此最小移动次数为 2。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(t * n) | 每个测试用例扫描数组两次：一次扫描第一个芯片，一次扫描最后一个芯片，然后一次计算之间的零。 每次扫描的时间复杂度为 O(n)。 |
 | 空间| O(n) | 仅存储输入数组。 除了循环变量之外没有其他数据结构。 |

 和`t <= 1000`和`n <= 50`，最坏情况下的操作计数为 50,000 次，完全在 2 秒限制之内。 内存使用可以忽略不计。 

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        first = a.index(1)
        last = len(a) - 1 - a[::-1].index(1)
        moves = sum(1 for i in range(first, last + 1) if a[i] == 0)
        output.append(str(moves))
    return "\n".join(output)

# provided samples
assert run("5\n8\n0 1 1 1 0 1 1 0\n6\n0 1 0 0 0 0\n6\n1 1 1 1 1 1\n5\n1 0 1 0 1\n9\n0 1 1 0 0 0 1 1 0\n") == "1\n0\n0\n2\n3"

# custom tests
assert run("2\n2\n1 0\n3\n0 1 0\n") == "0\n0"  # minimal n, single chip
assert run("1\n6\n0 0 1 0 1 0\n") == "2"  # zeros outside first/last ignored
assert run("1\n7\n1 0 0 0 0 0 1\n") == "5"  # all
```
