 ## 解决方案
 ## 问题理解

 我们得到一个数组`c`正整数和多个查询询问是否某些子数组`c`是_好_。 如果可以构造另一个数组，则子数组是好的`b`长度相同，满足三个条件：子数组和`b`匹配，子数组的每个元素都不同于对应的元素`b`，以及所有元素`b`是积极的。 

输入由多个测试用例组成。 每个测试用例提供数组`c`和一个查询列表，每个查询通过其起始索引和结束索引定义一个子数组。 如果子数组良好，则每个查询的输出为“YES”，否则为“NO”。 

约束很严格：所有数组的总长度和跨测试用例的查询总数可以达到 300,000。 这意味着任何为每个查询单独检查每个子数组元素的解决方案在最坏的情况下都会执行 10^10 次操作，这太慢了。 我们需要一种能够有效回答每个查询的方法，而无需每次都显式地重建子数组。 

当子数组仅包含单个元素时，会出现微妙的边缘情况。 在这种情况下，没有办法满足以下条件：`b_i ≠ a_i`，因为在保持总和不变的情况下，单个正整数不能与其自身不同。 任何忽略这一点的幼稚方法都会错误地声称长度为一的子数组是好的。 

## 方法

 暴力方法会尝试构造一个有效的数组`b`对于每个查询，通过迭代子数组并尝试分配与`a_i`同时保持总和一致。 对于长度为的子数组`m`，这需要`O(m)`每次查询的时间。 最坏的情况是对长度不超过 300,000 的数组进行 300,000 次查询，这会导致大约 10^10 次操作，这是不可行的。 

关键的观察结果是子数组中的实际值很大程度上与善良问题无关。 长度为 1 的子数组永远不会是好的，但任何长度为 2 或以上的子数组总是可以通过简单的重新分配技巧来变得好。 如果长度至少为 2，则始终可以将一个元素增加 1，并将另一个元素减少 1。这样可以保留总和，在所有原始元素均为正数的情况下保证正数，并确保所有元素`b_i ≠ a_i`。 

这将问题简化为简单的检查：如果子数组长度为 1，则答案为“否”。 否则，答案是“是”。 这种方法回答了每个查询`O(1)`读取输入后的时间。 前缀和甚至不是必需的，因为实际和不会限制超出琐碎正性和和保存条件的可行性，这些条件是通过重新分配满足的。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(子数组总长度) ≈ 10^10 | 每次查询 O(m) | 太慢了 |
 | 最佳 | O(n + q) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1.读取测试用例数量`t`。 对于每个测试用例，请阅读`n`和`q`，后跟数组`c`长度`n`。 
2. 对于每个查询，读取索引`l`和`r`。 计算子数组的长度为`r - l + 1`。 
3.如果长度为1，则打印“NO”，因为没有数组`b`可以满足`b_1 ≠ a_1`同时保留总和和积极性。 
4. 如果长度为2或更多，则打印“YES”，因为我们总是可以将一个元素向上调整1，另一个向下调整1，确保`b_i ≠ a_i`和总和相等。 

**为什么起作用**：可能使子数组不可能的唯一约束是长度为 1。对于较长的子数组，求和条件足够灵活，可以最小程度地调整元素以满足所有条件。 不变的是，对于任何长度 ≥ 2，至少有两个元素允许交换，在更改两个值的同时保留总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, q = map(int, input().split())
    c = list(map(int, input().split()))
    for _ in range(q):
        l, r = map(int, input().split())
        length = r - l + 1
        if length == 1:
            print("NO")
        else:
            print("YES")
```该解决方案使用有效地读取输入`sys.stdin.readline`。 对于每个查询，它计算子数组长度`O(1)`并应用简单的长度检查。 该程序避免了不必要的数组切片或求和计算，这使得它能够快速处理最大的输入大小。 正确处理的关键边界是长度为一的子数组。

 ## 边缘情况

 对于单元素子数组，例如`c = [42], query = 1 1`，算法计算`length = 1`并立即输出NO。 没有尝试构建`b`，避免错误接受。 

对于可能的最大子数组，例如`c`长度为300,000并查询`1 300000`,`length = 300000`直接触发“YES”，无需迭代或求和，确认解决方案有效处理上限。 

所有边缘情况，包括数组开头或结尾处的连续相等元素和子数组，都可以通过这个简单的长度检查正确处理。
