 ## 解决方案
 ## 问题理解

 我们得到了一系列持续时间，其中每个值代表 Vasya 需要背诵一节经文的一部分所需的时间。 他必须按从左到右的顺序背诵这些部分，并且他将获得相当于他在时间用完之前完成的部分的奖励。 侦听器仅停留固定的秒数，因此一旦累计时间超过此限制，之后的所有内容都无关紧要。 

有一种允许的放松：瓦西亚最多可以完全跳过一部分。 跳过会从序列中删除该部分，有效地让他“压缩”时间线，并可能在时间限制之前容纳更多部分。 

任务不仅仅是计算他可以容纳的最大部件数，而是决定跳过哪个部件以最大化该数量。 如果什么都不跳过是最佳的，我们输出 0。 

约束足够严格，每个测试用例的任何解决方案都必须是线性或接近线性的。 总元素数高达 100,000 个时，尝试删除每个元素并重新计算总数的 O(n²) 策略显然会失败，因为在最坏的情况下最多需要 1010 次操作。 这立即将我们推向前缀和和双指针或二分搜索风格的优化。 

一些边缘情况很容易处理不当。 如果整个数组已经符合时间限制，则无需跳过，答案必须为 0。例如，如果`a = [1, 2, 3]`和`s = 10`，所有零件都适合，任何跳过只会降低结果。 

当需要跳过但最佳跳过不在结尾附近时，会发生另一个棘手的情况。 例如，如果早期元素很大，跳过它们可以解锁许多小的后缀元素。 总是跳过最大元素或第一个溢出元素的天真贪婪在这里失败了。 

最后，在某些情况下，多个跳过选择会产生相同的最佳计数。 该问题允许任何有效答案，因此我们不需要超出一致性的平局逻辑。 

## 方法

 暴力破解的想法很简单：尝试跳过每个索引（包括不跳过任何索引），然后模拟在时间限制内可以获取多少个前缀元素。 对于每个候选跳跃位置，我们从左到右计算总和，忽略该索引。 每次模拟的成本为 O(n)，并且对所有 n 个可能性进行模拟会导致 O(n²)，这对于 10⁵ 元素来说太慢了。 

关键的观察结果是，答案仅取决于前缀和以及删除一个元素是否可以将截止点进一步向右移动。 如果我们固定一个以 r 结尾的前缀，则有效的条件是该前缀中所有选定元素减去最多一个跳过的元素的总和不得超过 s。 这就把问题变成了在删除其中的一个元素后找到总和≤ s 的最长前缀。 

我们可以计算一次前缀和。 然后对于每个位置 r，我们问：是否存在索引 i ≤ r 使得 prefix_sum[r] - a[i] ≤ s？ 这相当于查找是否存在元素a[i] ≥ prefix_sum[r] - s。 如果存在这样的元素，我们可以跳过它并保留r个元素。 

为了有效地回答这个问题，我们在当前前缀上维护一个数据结构，该结构跟踪最大值，并允许我们检索有效元素的索引。 由于我们只需要知道前缀中的任何元素是否足够大，因此我们可以在扩展 r 时跟踪最大值及其位置。 如果 prefix_sum[r] ≤ s，我们就直接取 r。 否则，我们检查是否 max(a[1..r]) ≥ prefix_sum[r] - s； 如果是，我们可以实现r，否则r是不可能的。 

这将问题减少到一次。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 太慢了|
 | 前缀+贪心检查| O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 从左到右扫描数组时计算前缀和，因为任何有效段在可能删除一个元素后始终是前缀。 
2. 跟踪到目前为止在前缀及其索引中看到的最大值，因为如果超出限制，这是删除的最佳候选者。 
3. 对于每个位置r，计算前缀的总和。 
4. 如果总和在限制 s 内，则将最佳答案更新为 r 且不删除，因为我们已经可以获取 r 元素。 
5. 如果总和超过 s，则计算所需的减少量`need = prefix_sum[r] - s`。 这是我们必须删除以使前缀有效的最小值。 
6. 如果前缀中的最大元素至少为`need`，则存在固定前缀的可移除元素，所以 r 可行。 
7. 跟踪可行的最大 r，并记住启用它的元素的索引，如果不需要删除，则记住 0。 

为什么有效：对于任何前缀，删除一个元素只会将总和减少该元素的值。 唯一重要的是前缀中的任何元素是否足够大以补偿溢出。 由于所有元素都是正的，因此删除单个足够大的元素对于修复可行性既是必要的，也是充分的。 这使得决策纯粹是前缀本地的，并且未来的元素不会影响是否可以实现给定的前缀。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, s = map(int, input().split())
        a = list(map(int, input().split()))
        
        pref = 0
        best_len = 0
        best_idx = 0
        
        max_val = 0
        max_idx = -1
        
        # prefix scan
        for i in range(n):
            pref += a[i]
            
            if a[i] > max_val:
                max_val = a[i]
                max_idx = i
            
            if pref <= s:
                best_len = i + 1
                best_idx = 0
            else:
                need = pref - s
                if max_val >= need:
                    best_len = i + 1
                    best_idx = max_idx + 1
        
        print(best_idx)

if __name__ == "__main__":
    solve()
```该实现保留一个运行前缀和和一个运行最大元素。 在每一步中，我们都会决定前缀是否已经有效，或者可以通过删除迄今为止看到的最大元素来使其有效。 如果两者都不成立，我们就不会更新最佳前缀长度。 

返回的索引对应于可以实现的最佳前缀，并且我们存储其删除启用它的元素的位置。 如果根本不需要删除，则存储的索引保持为 0。 

一个微妙的点是，我们永远不需要显式测试前缀内所有可能的删除，因为在决定可行性时只有最大的元素很重要：如果可以删除任何元素来修复总和，那么删除最大值总是足够或更好。

 ## 边缘情况

 当所有元素都已经符合限制时，前缀永远不会超过 s，因此算法不断更新 best_len，而 best_idx 保持为 0。 对于输入`n=3, s=100, a=[1,2,3]`，每次迭代都满足`pref <= s`，最终输出为0，满足不需要跳过的要求。 

当第一个元素太大时，跳过它成为继续进行的唯一方法。 为了`n=3, s=3, a=[2,2,2]`，第一个前缀已经起作用，但扩展需要跳过前 2 个前缀以最大化覆盖范围。 该算法正确地识别出删除索引 1 会启用更长的前缀。 

当存在多个大候选者时，存储的最大值始终跟踪最佳的可移动元素，因此即使有多个选择可以工作，算法也会一致地选择有效的跳过，因为任何正确的索引都会被接受。
