 ## 解决方案

 ## 问题理解

 我们得到了几个独立的测试用例。 每个测试用例描述三堆彩色灯：红色、绿色和蓝色。 任务是决定我们是否可以将所有灯排列成一行，以便没有两个相邻的灯共享相同的颜色，同时每个灯恰好使用一次。 

换句话说，我们想知道是否存在三个符号的多重集的排列，使得相同的符号永远不会相互接触。 每个测试用例只是对这种重新安排的可行性检查。 

计数的约束很大，高达$10^9$，但测试用例的数量很少，最多 100 个。这立即排除了任何尝试显式构造序列或逐步模拟放置的方法。 任何基于构造的模拟都需要与灯总数成正比的时间，在最坏的情况下可能达到数十亿。 

问题的结构表明只有相对频率才重要。 除了最大堆与其余堆之间的比较之外，绝对大小无关紧要。 

一些边缘模式值得尽早考虑。 

如果一种颜色占主导地位，例如1个红色，10个绿色，2个蓝色，那么在放置所有非绿色灯之后，无法避免连续放置绿色，因为其他颜色没有足够的“间隙”。 

如果所有计数都相等，例如 3 3 3，则显然存在有效的交替排列。 

如果两种颜色较小而一种颜色稍大，例如 2 1 1，我们仍然可以通过始终将较大的颜色与其他颜色分开来将它们交错。 

严重故障情况是当最大计数与其他两个计数之和相比太大时。 

## 方法

 蛮力策略将尝试明确地建立这种安排。 一种方法是从一个空序列开始，然后重复放置与上次放置的灯颜色不同的剩余灯颜色。 在每一步中，我们都会尝试除前一种颜色之外的所有可用颜色，并在可能的情况下选择一种颜色。 

这种贪婪的构造是可行的，但即使仔细实现，它也会对长度为$r + g + b$，可以大到$3 \cdot 10^9$。 这使得它完全不可行。 即使存储或迭代这样的序列也是不可能的。 

关键的观察结果是，整个问题由一个约束控制：我们需要足够的“分隔符”来防止相同的颜色变得相邻。 两个较小的堆一起充当最大堆的分隔物。 

如果我们对计数进行排序$a \ge b \ge c$，我们可以想到将最大的颜色放在前面。 在连续放置这种主色之间，我们至少需要一盏非主色灯。 这意味着我们至少需要$a - 1$可用的分隔位置，这正是$b + c$提供。 

因此，条件简化为最大的一堆是否超过其他两堆的总和超过一。 

更准确地说，当$a \le b + c + 1$。 

这个单一的不等式捕获了所有有效的交错，其他一切都由此而来。

 | ---| ---| ---| ---|
 | 贪婪构造| O(r+g+b) | O(r+g+b) | 太慢了|
 | 排序+不等式检查| O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 对于每个测试用例，我们仅通过推理计数来确定是否存在有效的排列。 

1. 读取代表每种颜色灯的数量的三个整数。 

最初的顺序并不重要，因为我们会将其标准化。 
2. 对三个值进行排序，使得最大的计数变为$a$，另外两个是$b$和$c$。 

此步骤隔离最有可能导致相邻问题的颜色。 
3. 检查最大计数与其他计数相比是否太大。 

具体来说，测试是否$a > b + c + 1$。 

如果这个不等式成立，我们返回“否”。 原因是，即使我们完美地交替，两种较小的颜色也只能创造出$b + c$间隙，不足以分隔所有出现的最大颜色。 
4. 否则，返回“是”。 

在这种情况下，较小的颜色足以分离主色的出现，并且我们始终可以通过将它们分布在大块之间来构建有效的序列。 

### 为什么它有效

 排列问题完全取决于可以创建多少个“槽”来分隔相同的符号。 任何有效的序列都必须将最常见颜色的出现放在不同的位置，并且每次分离都需要至少一盏不同颜色的灯。 可用分隔符的总数恰好是其他两种颜色的总和。 如果这个总和太小，无论怎样安排，冲突都不可避免。 如果它足够大，我们总是可以贪婪地交错，而不必强迫两个相同的邻居。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    r, g, b = map(int, input().split())
    a, b1, c = sorted([r, g, b], reverse=True)
    if a > b1 + c + 1:
        print("No")
    else:
        print("Yes")
```该实现直接反映了数学条件。 排序确保我们始终将最常见的颜色视为潜在的瓶颈。 比较`a > b1 + c + 1`编码从间隙计数得出的不可能性条件。 每个测试用例的其他时间都是恒定的，因此即使在最大输入大小下，该解决方案也非常高效。

 ## 边缘情况

 一个微妙的情况是最大的一堆恰好比其他堆的总和多一。 例如，4 1 1 排序为 (4, 1, 1)。 这里$b + c = 2$， 和$a = 4$， 所以$a > b + c + 1$变成$4 > 3$，这是事实，所以这是不可能的。 该算法正确地拒绝它，因为没有足够的分隔符。 

另一种情况是所有计数都相等。 对于 5 5 5，条件变为$5 \le 10 + 1$，这很简单。 该结构保证了循环交织的存在，并且不等式捕获了这一点而无需构造它。 

即使两种颜色与一种大颜色相比非常小，该规则也可以纯粹通过算术比较来清晰地区分可解和不可解的情况，从而避免任何显式排列的需要。
