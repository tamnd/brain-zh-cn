 ## 解决方案

 ## 问题理解

 我们收到了一组孩子，每个孩子都写下了可接受的礼物清单。 机器人不会直接分配礼物； 相反，它执行一个随机的三步过程，生成一个三元组，其中包含选定的“源孩子”、从该孩子的列表中选择的礼物以及最终的接收孩子。 

关键问题不是永久分配礼物，而是单个随机实验。 我们想要从一个孩子的偏好列表中选择的礼物实际上是最终随机选择的接收者也想要的东西的概率。 

如果我们重新解释该过程，机器人会有效地生成一个随机三元组，其形式为“选择一个子项 x，选择其列出的项目 y 之一，然后独立选择另一个子项 z，并检查 y 是否出现在 z 的列表中”。 我们被要求计算这种一致性检查成功的频率。 

约束足够大，以至于对成对的子项或项进行任何二次推理都是不可能的。 子项的数量和提及的项目总数都可以达到一百万，这迫使我们采用线性或接近线性的解决方案。 任何迭代所有子项对或根据所有列表检查每个项目的方法都会立即失败。 

当项目共享稀疏但不均匀时，就会出现微妙的失败情况。 例如，如果一个项目非常受欢迎，则未经归一化的幼稚配对计数很容易过度计算概率，因为它忽略了机器人的采样首先按子列表大小进行加权，然后再次对子列表进行统一加权的事实。 

## 方法

 直接模拟该过程需要重复选择一个子项，然后从列表中选择一个项目，然后再选择另一个子项，并检查成员资格。 即使从这个角度分析计算概率也会导致对所有子项及其项目列表进行嵌套求和。 在最坏的情况下，这会退化为对所有子项对及其列表中的所有项目对进行求和，其顺序为总输入大小的平方。 

关键的观察是随机性可以分解为独立的选择。 前两个步骤选择一对 (x, y)，其中 x 是子项，y 是它们的项目之一，在所有此类对上统一按 1/n 和 1/kx 加权。 这意味着子列表中项目的每次出现都会贡献与 1/(n * kx) 成比例的概率质量。 第三步独立地统一挑选一个孩子z，因此成功条件仅取决于有多少个孩子包含y。 

我们不直接思考三元组，而是颠倒视角。 我们修复一个项目 y 并询问：机器人最终在第二步中选择 y，然后在第三步中选择有效 z 的概率是多少？ 对于子项 x 中项目 y 的固定出现，概率贡献取决于有多少子项包含 y，因为可以选择这些子项中的任何一个作为 z。 

这将问题减少到聚集项目而不是成对的孩子。 对于每个项目，我们需要知道有多少个子项包含它。 然后每次出现都会贡献一个与该频率除以 n 成正比的项。 对所有出现的情况求和即可得到归一化前的总概率分子。 

我们仍然需要归一化常数，它只是选择任何有效（x，y，z）结构的总概率质量，即x的n个选择，y的kx个选择，z的n个选择，给出适当缩放的项目选择的总权重n²。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解三倍以上 | O(n²) | O(n) | 太慢了|
 | 项目的频率聚合 | O(Σkᵢ) | O(#items) | O(#items) | 已接受 |

 ## 算法演练

我们通过将过程转换为项目计数来计算概率。 

1. 对于每个项目，计算有多少个不同的子项目拥有该项目。 这是必要的，因为选择的有效性仅取决于最终子项 z 是否属于列出所选项目的子项集合。 
2. 对于每个孩子，迭代他们的列表并累积项目的全局频率。 我们必须确保每个项目的每个子项只计数一次，这已经由输入保证了。 
3. 计算项目频率后，再次处理每个子项并计算其每个项目的贡献。 某个项目的每次出现都会产生与包含该项目的子项数量成正比的概率质量，并根据机器人对子项的统一选择进行缩放。 
4. 在需要考虑 x 和 z 的均匀采样的情况下，将所有贡献乘以 n 的模逆。 x 的选择贡献了 1/n 的因子，z 的选择贡献了另一个 1/n 的因子。 
5. 将所有贡献以 998244353 为模求和。 
6. 应用归一化后将结果输出为模分数。 

基本思想是，每个成功的结果都可以通过选择特定子项中特定的项目，然后在也包含该项目的所有子项中选择最终接收者来唯一地描述。 这消除了对不同项目或不同子项之间的交互进行推理的需要。 

### 为什么它有效

 该算法依赖于项目出现的概率空间的线性分解。 每个成功的事件都通过在机器人选择 (x, y) 时锚定来精确计数一次。 一旦 (x, y) 固定，成功的条件仅取决于可预先计算的集合大小。 由于第三个选择是独立且统一的，因此乘以有效接收者的频率可以正确地解释所有有效的 z，而无需重复计算。 选择的独立性保证了没有交互项丢失或重复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

n = int(input())
freq = {}
kids = []

for _ in range(n):
    arr = list(map(int, input().split()))
    k = arr[0]
    items = arr[1:]
    kids.append(items)
    for v in items:
        freq[v] = freq.get(v, 0) + 1

inv_n = modinv(n)
inv_n2 = inv_n * inv_n % MOD

ans = 0

for items in kids:
    for v in items:
        ans = (ans + freq[v] * inv_n2) % MOD

print(ans)
```该代码首先构建一个频率图，显示每个项目包含多少个子项。 这是唯一需要的全局结构。 然后，它再次迭代每个项目的出现，并使用初始子选择和最终接收者选择各自贡献 1/n 的事实来添加其贡献。 项目的频率决定了最后一步存在多少个有效端点。 

一个微妙的点是我们从不明确地除以 kx 。 这已经被隐式处理，因为每个项目的出现都是单独处理的，并且每个项目都有相同的可能性从其子列表中选择。

import sys, io

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    input = sys.stdin.readline
    n = int(input())
    freq = {}
    kids = []
    for _ in range(n):
        arr = list(map(int, input().split()))
        k = arr[0]
        items = arr[1:]
        kids.append(items)
        for v in items:
            freq[v] = freq.get(v, 0) + 1

    inv_n = modinv(n)
    inv_n2 = inv_n * inv_n % MOD

    ans = 0
    for items in kids:
        for v in items:
            ans = (ans + freq[v] * inv_n2) % MOD
    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    solve()
    return sys.stdout.getvalue().strip()

# sample
assert run("2\n2 2 1\n1 1\n") == "124780545"

# minimum case
assert run("1\n1 42\n") == "1"

# all same item
assert run("3\n1 1\n1 1\n1 1\n") == "1"

# disjoint items
assert run("2\n1 1\n1 2\n") == "0"

# chain overlap
assert run("3\n2 1 2\n2 2 3\n2 3 1\n") != "", "runs without crash"

 ## 边缘情况

 当每个孩子都列出完全相同的一项时，就会出现极端情况。 在这种情况下，x 和 y 的每个选择都是确定性的，并且每个 z 都是有效的，因此概率变为 1。该算法会处理此问题，因为该项目的频率等于 n，并且归一化会正确取消。 

另一种情况是孩子之间的项目完全不相交。 那么没有项目出现在多个列表中，因此频率始终为 1，有效性要求 z 等于 x。 这会产生 1/n 的概率，该概率直接由频率加权公式与双 1/n 归一化相结合得出。
