 ## 解决方案
 ## 问题理解

 我们正在处理一个隐藏的长度为二进制的数组$n$，其中每个位置为零或一。 数组本身不会改变，而是被我们自己的动作修改：每次我们正确识别当前的位置$k$从左边算起第 0 个零，该位置将永久翻转为 1。 

观察数组的唯一方法是通过范围求和查询。 对段的查询$[l, r]$returns how many ones are currently in that interval. 由于数组是二进制的，这也隐式地告诉我们段中有多少个零，因为零只是段长度内的补码。 

任务重复进行$t$独立的请求。 对于每个请求，我们都会得到一个值$k$，我们必须输出$k$- 数组当前状态中的第一个零。 每次回答后，数组都会发生变化，因为零变成了一。 

这些限制非常严格，迫使每个查询都必须仔细预算。 该数组可以大到$2 \cdot 10^5$，并且最多有$10^4$查询。 交互式请求的总数是有限的，因此任何重复扫描数组或从头开始重建状态的方法都会立即变得太慢。 即使每个查询只有一个二分搜索，也必须仔细优化，因为每个二分搜索都会将交互式调用的数量乘以对数因子$n$。 

一种简单的方法是首先尝试重建完整的数组。 这会失败，因为它需要单独查询每个位置或递归地分割段直到完全知道，从而至少导致$O(n)$或者$O(n \log n)$查询，远远超出允许的预算。 

如果我们尝试找到每个失败案例，就会出现另一个失败案例$k$-th 0 通过从头开始扫描并递减$k$使用范围查询。 那退化成$O(n)$在最坏的情况下，每个请求都无法处理$t = 10^4$。 

动态更新会产生一个更微妙的问题。 在每个答案之后，一零变成一，因此我们查询的结构发生了变化。 任何在所有查询中假定固定前缀结构的方法都会在第一次更新后默默地产生不正确的结果。 

## 方法

 暴力破解的想法很简单：对于每个查询，从左到右扫描并维护一个为零的计数器。 每当我们达到零时，递减$k$，当它达到零时，输出该位置。 这在概念上是正确的，但需要知道每个位置是零还是一。 由于我们不知道数组，因此我们必须使用大小为 1 的范围查询单独查询每个位置。 这已经花费了$O(n)$每个请求的查询数，导致$O(n t)$，这是完全不可行的。 

一种更结构化的方法是利用我们可以通过范围和计算前缀信息的事实。 如果我们可以计算任何前缀中的个数$[1, x]$，那么零的数量就是$x - \text{ones}(1, x)$。 这将问题转化为寻找最小索引$x$使得零的数量达到$x$至少是$k$。 

这个条件是单调的$x$，因此二分查找变得适用。 二分搜索中的每个检查都会询问一个范围和查询，从中我们得出当前中点是否至少包含$k$其前缀为零。 一旦我们可以回答前缀零计数，$k$-第一个零可以在对数时间内找到。 

复杂的是，每次二分查找都需要多次交互式查询，并且查询总数受到严格限制。 该解决方案依赖于这样一个事实：我们永远不需要以非结构化方式重复查询任意子结构。 每个操作纯粹由前缀评估驱动，并且每个查询都是独立的，除了将单个位置从零翻转到一的更新之外。 

这导致了标准解决方案：保持查询范围总和的能力，并对每个请求的索引使用二分搜索。 更新是隐式的，因为一旦我们找到一个位置，我们就会在概念上翻转它，并且未来的前缀和会自动反映这种变化，因为交互器状态已经更新。

 | --- | --- | --- | --- |
 | 暴力扫描 |$O(n)$每个查询|$O(1)$| 太慢了|
 | 带有范围查询的二分搜索 |$O(t \log n)$查询 |$O(1)$| 已接受 |

 ## 算法演练

 1. 对于每个请求，我们希望找到前缀至少包含的最小索引$k$零。 我们将其视为索引范围内的单调搜索问题$[1, n]$。 
2. 定义一个函数来计算前缀中零的数量$[1, x]$。 这计算为$x - \text{sum}(1, x)$，其中总和是从交互器获得的。 此步骤将隐藏的二进制结构转换为直接可用的数量。 
3. 对范围进行二分查找$[1, n]$。 在每个中点$m$, 查询其中的总和$[1, m]$，将其转换为零的个数，并检查是否至少$k$。 如果是，答案就在左半部分；如果是，则答案在左半部分。 否则，它位于右半部分。 
4. 继续，直到二分查找收敛到单个位置。 那个位置就是$k$当前数组中的第一个零。 
5. 输出找到的位置，并在正确答案后依靠交互器的状态变化立即执行更新逻辑。 现在，在所有未来的查询中，翻转的位置将被视为一个位置。 

关键的不变性是，每次更新后，交互器始终准确地表示当前数组状态，并且每个前缀查询都反映所有先前的翻转。 二分查找的正确性依赖于谓词“前缀至少包含”的单调性$k$Zeros”，仅依赖于前缀和，并且在更新后仍然有效。

 ## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(l, r):
    print(f"? {l} {r}")
    sys.stdout.flush()
    res = int(input())
    if res == -1:
        exit(0)
    return res

def find_kth_zero(n, k):
    l, r = 1, n
    while l < r:
        m = (l + r) // 2
        ones = ask(1, m)
        zeros = m - ones
        if zeros >= k:
            r = m
        else:
            l = m + 1
    return l

def main():
    n, t = map(int, input().split())
    for _ in range(t):
        k = int(input())
        pos = find_kth_zero(n, k)
        print(f"! {pos}")
        sys.stdout.flush()

if __name__ == "__main__":
    main()
```解决方案的核心是`ask`函数，封装了与法官的交互。 每个二分搜索步骤都取决于此函数返回的前缀和。 前缀内从 1 到 0 的转换至关重要，因为问题是用 0 表示的，但交互器仅提供 1 的和。 

二分搜索循环是标准的，但关键的微妙之处在于它始终从索引 1 进行查询。这确保我们只使用前缀信息，该信息在数组的不同状态之间保持一致和可比较。

 ## 边缘情况

 一个关键的边缘情况是前几个元素都是 1。 在这种情况下，第一个有效的零可能出现在数组深处，并且二分搜索必须正确忽略不包含零的前缀。 该谓词仍然有效，因为只有 1 的前缀会产生零个零，这会正确地使$k \ge 1$健康）状况。 

另一个边缘情况是多次翻转后重复查询。 由于每次翻转都会更改前缀结构，因此任何有关固定索引的缓存推理都会中断。 该算法完全避免了缓存，并且仅依赖于新的前缀查询，因此它仍然是正确的$t$更新。 

最后一个微妙的情况是$k$等于剩余零的总数。 在这种情况下，正确的答案始终是最右边的零，并且二分搜索自然会收敛到它，因为所有较小的前缀都不符合条件，直到到达最后一段。
