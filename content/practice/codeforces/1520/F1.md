 ## 解决方案
 ## 问题理解

 给定一个隐藏的二进制数组，长度为$n$。 我们无法直接看到数组。 相反，我们可以在任意时间间隔进行查询$[l, r]$，系统返回该段中的个数。 根据这些信息，我们必须确定$k$从左边算起第一个零。 

由于数组仅包含零和一，因此范围求和查询有效地告诉我们该段内有多少个。 如果我们知道一个线段的长度及其总和，我们也可以推断出其中有多少个零，因为零只是缺失的。 

交互限制很严格，最多只能进行 20 个查询。 数组大小最大可达$2 \cdot 10^5$，所以线性扫描是不可能的。 任何有效的解决方案都必须使用对数数量的查询来找到答案，这会立即建议对位置进行二分搜索。 

关键的难点是我们不是在寻找一个固定值，而是在寻找累计零个数达到的位置$k$。 这是隐藏在范围总和查询后面的基于前缀的条件。 

一个天真的错误是认为我们可以测试各个位置，直到找到合适的位置。$k$- 第 0 个。 这将需要最多$O(n)$最坏情况下的查询，远远超出了限制。 另一个微妙的错误是将查询结果误解为直接访问零； 它只给出 1，因此忘记通过段长度进行转换会导致不正确的前缀逻辑。 

例如，如果数组是$[1, 0, 1, 1, 0, 1]$和$k=2$，答案是位置 5。简单的扫描会检测位置 2 和 5 处的零，但如果没有范围推理，许多解决方案无法有效地构建此结构。 

## 方法

 暴力破解的想法很简单：从左向右行走，通过查询每个位置或前缀来计算零。 每次我们需要知道一个位置是否为零时，我们都会单独查询它。 这在逻辑上是有效的，因为每个查询都会隔离一个元素，但它需要最多$n$每个测试用例的查询。 和$n$最多$2 \cdot 10^5$，这太慢了。 

关键的观察是前缀中零的数量是单调的。 如果我们定义一个函数$Z(x)$作为 0 的数量$[1, x]$， 然后$Z(x)$仅增加为$x$增加。 我们正在寻找最小的位置$Z(x) \ge k$。 这正是二分查找条件。 

我们不能直接查询零，但我们可以从一计算它们。 对于前缀$[1, x]$，如果我们查询 1 的总和，那么零就是$x - \text{ones}(1, x)$。 这给了我们一个可以进行二分搜索的单调函数。 

因此，问题简化为对位置执行二分搜索，使用范围和查询来评估是否$k$第一个零位于中点的左侧或右侧。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力扫描 |$O(n)$查询 |$O(1)$| 太慢了|
 | 带查询的二分搜索 |$O(\log n)$查询 |$O(1)$| 已接受 |

 ## 算法演练

 我们想要找到最小的索引$x$使得至少有$k$前缀中的零$[1, x]$。 

1. 初始化搜索边界$l = 1$,$r = n$。 这些代表了答案必须所在的范围。 
2. 虽然$l < r$, 计算中点$m = (l + r) // 2$。 我们正在测试答案是在左半部分还是右半部分。 
3.查询分段总和$[1, m]$。 Let this be$S$。 该前缀中零的数量是$m - S$。 这将问题从“基于个数的反馈”转变为直接归零计数。 
4. 如果$m - S \ge k$，那么$k$-第一个零位于或之前$m$，所以我们移动右边界：$r = m$。 否则，它严格位于右侧，所以我们设置$l = m + 1$。 
5. 当循环结束时，$l = r$是前缀至少包含的最小位置$k$零。 这个立场就是答案。 

关键的不变量是，在每一步中，真正的答案都在里面$[l, r]$，并且谓词“前缀至少包含$k$“zeros”是单调的，一旦一个前缀满足条件，所有更大的前缀也满足它，所以二分查找是有效的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def ask(l, r):
    print("?", l, r)
    sys.stdout.flush()
    s = int(input().strip())
    if s == -1:
        sys.exit(0)
    return s

n, t = map(int, input().split())

for _ in range(t):
    k = int(input().strip())

    l, r = 1, n
    while l < r:
        m = (l + r) // 2
        ones = ask(l, m)
        zeros = (m - l + 1) - ones

        if zeros >= k:
            r = m
        else:
            k -= zeros
            l = m + 1

    print("!", l)
    sys.stdout.flush()
```该实现执行二分搜索，但通过跟踪向右移动时“消耗”了多少个零来进行稍微优化。 我们没有重新计算完整的前缀条件，而是调整$k$当我们消除左边的段时，使逻辑与缩小的搜索窗口一致。 

交互式处理至关重要：每个查询都会立即刷新，如果收到 -1，我们就会终止。

 ## 边缘情况

 一个关键的边缘情况是当数组以多个开始时。 例如，$[1, 1, 1, 0]$和$k=1$。 二分搜索必须通过识别早期前缀包含零个有效零来正确地跳过所有前导前缀。 谓词`zeros >= k`直到最后一段之前都保持 false，确保搜索正确折叠到最终索引。 

另一种边缘情况是零在开始时密集排列，例如$[0, 0, 0, 1, 1]$和$k=2$。 这里，正确的答案在前半部分内，并且算法必须始终如一地尽早丢弃右半部分。 前缀零计数的单调性确保一旦中点前缀至少包含$k$零，所有较大的索引仍然是有效的候选者，因此没有有效的答案被意外排除。
