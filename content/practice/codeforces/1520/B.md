 ## 解决方案
 ## 问题理解

 我们有多个查询，每个查询由一个正整数组成$n$。 对于每个$n$，我们需要计算有多少个数字在 1 到$n$所有数字的十进制表示形式都相同。 

这些“普通”数字具有非常严格的结构。 每个有效数字都是通过从 1 到 9 中选择一个数字并重复一次或多次而形成的。 因此，有效示例包括 7、88、444 和 999999999，而排除 10、101 或 123 等数字，因为至少有两位数字不同。 

约束条件$n \le 10^9$表示每个数字最多有 10 位数字。 这是关键的结构限制：可能的普通数总体上只有很少的数量，并且它们在所有整数的范围内极其稀疏。 

一个简单的方法是检查从 1 到$n$，验证所有数字是否相等。 这需要检查最多$10^9$最坏情况下每个查询的数量，这远远超出了给定的可接受的限制$t \le 10^4$。 即使每个测试用例进行线性扫描也是不可能的。 

边缘情况出现时$n$很小或与普通数字完全匹配。 例如，如果$n = 5$，答案是 5，因为每个个位数都是普通数。 如果$n = 10$，答案仍然是 9，因为 10 并不普通。 仅根据数字长度进行计数的粗心方法可能会错误地包含 10 或其他混合数字。 

主要的微妙之处在于认识到答案并不依赖于分布或算术属性$n$，但纯粹是计算一小部分结构化的候选人。 

## 方法

 暴力解决方案将从 1 迭代到$n$，将每个数字转换为字符串，并检查所有字符是否相同。 这是直接且正确的，因为它直接遵循定义。 然而，其成本与$n \log n$由于数字检查，每个测试用例立即变得不可行$n$达到$10^9$和$t$很大。 

关键的观察是普通数字具有固定的组合结构。 对于从 1 到 9 的每个数字，我们可以构造 1、11、111、1111 等数字。 对于固定长度$k$，正好有 9 个普通数字：1 到 9 的每个数字都有一个。然后问题就简化为计算有多少个这样的数字小于或等于$n$。 

我们不迭代所有整数，而是仅生成这些结构化候选者。 最多有 9 个数字，最多有 10 个长度，因此候选总数以 90 为界。这将每个查询变成对一个微小固定集合的恒定时间扫描。 

蛮力之所以有效，是因为它会明确地检查每个数字，但会失败，因为宇宙很大。 普通数字完全由数字选择和长度决定的观察结果使搜索空间从线性崩溃$n$到恒定大小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n \log n)$每个测试用例|$O(1)$| 太慢了|
 | 最佳 |$O(1)$每个测试用例|$O(1)$| 已接受 |

 ## 算法演练

 我们利用这样一个事实：每个普通数字都可以通过选择一个数字并重复它来生成。 

1. 预先计算直到$10^9$通过迭代从 1 到 9 的数字选择并构建长度不断增加的重复数字。 

每次构造都是从0开始，重复添加相同的数字，从而形成数值的几何增长。 
2. 将所有生成的值存储在列表中。 
3. 对列表进行排序，以便我们可以使用二分搜索或简单计数来回答查询。 
4. 对于每个查询$n$，计算有多少个预先计算的值小于或等于$n$。 

计数步骤实际上是对已排序静态数组的前缀查询，这可以通过二分搜索在对数时间内完成，尽管线性扫描超过 90 个元素就足够了。 

### 为什么它有效

 每个普通数字都唯一对应一对（数字，长度）。 不存在重复项，因为不同的数字长度结构总是产生不同的整数。 由于我们在数字限制内详尽地生成所有这些对$10^9$，预先计算的集合与有效答案的范围完全匹配。 任意的最终计数$n$因此只是这个完整集合中不超过的元素数量$n$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

# Precompute all ordinary numbers up to 1e9
ordinaries = []

for digit in range(1, 10):
    val = 0
    for _ in range(10):  # max 10 digits because n <= 1e9
        val = val * 10 + digit
        ordinaries.append(val)

ordinaries.sort()

t = int(input())
for _ in range(t):
    n = int(input())
    
    # count how many are <= n
    cnt = 0
    for x in ordinaries:
        if x <= n:
            cnt += 1
    print(cnt)
```该代码通过固定一个数字并重复附加它来构造所有候选普通数。 每个生成的值都存储在一个全局列表中，然后对该列表进行排序以进行单调查询。 

对于每个测试用例，我们迭代预先计算的列表并计算有多少值不超过$n$。 由于列表大小仅为 90，因此这实际上是每个查询的恒定时间。 

一个常见的实施错误是尝试生成仅达到数字长度的数字$n$每个查询都是动态的。 这不必要地使逻辑变得复杂，并且在处理诸如十的幂之类的边界值时存在相差一错误的风险。 预计算避免了所有此类问题。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    ordinaries = []
    for digit in range(1, 10):
        val = 0
        for _ in range(10):
            val = val * 10 + digit
            ordinaries.append(val)
    ordinaries.sort()

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        cnt = 0
        for x in ordinaries:
            if x <= n:
                cnt += 1
        out.append(str(cnt))
    return "\n".join(out)

# provided samples
assert run("6\n1\n2\n3\n4\n5\n100\n") == "1\n2\n3\n4\n5\n18"

# minimum size
assert run("1\n1\n") == "1"

# boundary around 10
assert run("2\n9\n10\n") == "9\n9"

# exact ordinary number
assert run("1\n111\n") == "3"

# large value
assert run("1\n1000000000\n") == "90"

 ## 边缘情况

 对于$n = 10$，该算法仅计算 1 到 9，因为 10 不是重复数字。 预先计算的列表包含 11，因此在计数时，11 被正确排除，因为它超出了$n$。 

为了$n = 999999999$，包括所有一位数到九位重复数字。 该算法迭代所有 90 个预先计算的值并对它们进行全部计数，得出 90。 

对于$n = 1$，只有列表中的第一个元素有贡献。 由于所有其他生成的值都大于 1，因此结果仍然为 1。
