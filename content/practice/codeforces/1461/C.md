 ## 解决方案
 ## 问题理解

 我们给出了一个初始排列和一系列概率运算。 每个操作都集中于排列的前缀，并独立地以给定的概率对该前缀进行排序。 如果操作“触发”，则前缀将完全排序； 否则它保持不变。 操作按顺序应用，每个决策都是独立的。 

任务是计算所有操作完成后整个排列排序的概率。 

关键的困难在于，对前缀进行排序会对以后的状态产生全局影响，但只是以结构化的方式：一旦前缀被排序，它就永远不会再次变得“未排序”。 这就造成了一个单调的过程，进展只会向前推进。 

这些约束最多允许 10^5 个操作和元素，因此每个测试用例的任何解决方案都必须是线性的。 这立即排除了模拟所有结果或维持排列的完整概率分布，因为这些会组合爆炸。 

一个常见的错误是将每个操作视为独立地对整个数组的正确性做出贡献。 这会失败，因为如果之前已经对较大的前缀进行了排序，则稍后对较短前缀的操作可能无关紧要。 

## 方法

 强力解释将模拟成功操作的每个子集，计算结果排列，并检查它是否已排序。 对于 m 个操作，这会导致 2^m 个场景，每个场景都需要模拟前缀排序。 这是不可行的，因为 m 可以是 10^5。 

关键的观察是我们不需要完整的排列状态。 重要的是排列尚未保证排序的最早位置。 一旦覆盖所有放错位置的元素的前缀被排序，整个数组就被排序了。 

这导致了一个动态过程：我们跟踪仍然需要“修复”的最右边的位置，并更新该位置由于成功的前缀排序而变得不相关的概率。 

该结构将问题简化为操作上的线性 DP，其中每个操作要么有助于减少未解析的后缀，要么根据其前缀长度而无关。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^m·n) | O(2^m·n) | O(n) | 太慢了 |
 | 前缀边界上的 DP | O(n + m) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1、找准定位`bad`，这是排列与恒等排列不同的最右边的索引。 如果数组已经排序，则答案立即为 1，因为没有随机性可以破坏它。 
2. 如果数组已排序，则返回 1。否则，所有概率质量都经过固定索引的过程，直到`bad`。 
3. 初始化累加器`ans = 1`。 这将表示在处理所有相关操作后数组保持未排序的概率。 
4. 按顺序迭代操作。 对于每个操作`(r, p)`，仅操作`r >= bad`重要的是，因为只有它们才能影响最后一个错误的位置。 
5. 如果`r < bad`，完全跳过该操作，因为它无法修复关键后缀。 
6. 如果`r >= bad`，更新我们修复数组失败的概率。 操作成功的概率`p`，这意味着它对前缀进行排序并可能修复数组。 我们保持失败状态的概率乘以`(1 - p)`。 
7. 处理完所有操作后，数组排序的概率为`1 - ans`。 

为什么它有效：一旦覆盖最后一个不正确位置的前缀被排序，整个排列就会永久排序。 因此，只有达到该边界的操作才是重要的，其效果是故障概率的独立乘法降低。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        bad = 0
        for i in range(n):
            if a[i] != i + 1:
                bad = i + 1

        if bad == 0:
            for _ in range(m):
                input()
            print("1.000000")
            continue

        fail = 1.0

        for _ in range(m):
            r, p = input().split()
            r = int(r)
            p = float(p)

            if r >= bad:
                fail *= (1 - p)

        print(f"{1 - fail:.6f}")

if __name__ == "__main__":
    solve()
```该解决方案首先确定排列未排序的最后一个位置。 当阵列固定时，该位置完全表征。 任何未达到此位置的操作都是无关紧要的。 在相关操作中，每个操作都独立地通过乘法因子降低未排序的概率。 

一个微妙的点是浮点精度。 由于要求概率的误差容限高达 1e-6，因此标准双精度就足够了。 另一个重要的细节是尽早跳过不相关的前缀操作； 包含它们不会改变正确性，但可能会引入不必要的浮点乘法。

 ### 示例 1

 输入：```
n = 4
a = [4, 3, 2, 1]
operations = [(1, 0.3), (3, 1.0), (4, 0.6)]
```这里`bad = 4`。 

| 操作| r | p| 相关| 失败|
 | --- | --- | --- | --- | --- |
 | 开始 | - | - | - | 1 |
 | (1,0.3) | (1,0.3) | 1 | 0.3 | 0.3 没有| 1 |

 | (4,0.6) | (4,0.6) | 4 | 0.6 | 0.6 是的 | 0.4 | 0.4

 最终答案是`1 - 0.4 = 0.6`。 

这仅显示到达最后一个不正确索引的操作有贡献。 

### 示例 2

 输入：```

a = [1,2,3,4]
operations = [(2,0.5),(4,0.1)]
```这里`bad = 0`，所以无论操作如何，答案都会立即为 1。 

这证实了一旦数组最初排序，随机性就不会破坏正确性。

 ## 边缘情况

 当排列已经排序时，算法无需处理概率即可正确返回 1，因为不需要任何操作即可达到目标状态。 

当仅对小前缀进行排序时，它们都不会到达最后一个错误位置，因此失败概率的乘积仍为 1，正确地产生答案 0。 

当存在多个大前缀操作时，它们在故障空间中独立相乘，并且算法正确地模拟它们的组合效果，而不会重复计算。
