 ## 解决方案
 ## 问题理解

 我们从一个数组开始，并重复应用非常具体的分割规则。 

对于任何当前数组，计算$$mid = \left\lfloor \frac{\min + \max}{2} \right\rfloor$$所有值最大为`mid`组成一组，所有值大于的元素`mid`形成另一个。 分割后，我们保留两组中的一组并丢弃另一组。 

对于每个查询值`s`，我们必须确定是否存在某种此类选择的序列，该序列会产生一个元素总和恰好为的数组`s`。 

最重要的观察结果是，分裂仅取决于价值，而不取决于位置。 相对顺序被保留，但在对数组进行排序后，每个分割都变成了连续值范围的分割。 这将这个过程变成了排序数组的递归分区。 

约束足够大，我们无法独立模拟每个查询。 在所有测试用例中，数组元素总数和查询总数最多均为`10^5`。 周围有任何解决方案`O(nq)`会太慢，因为它可能需要大约`10^{10}`最坏情况下的操作。 我们需要一些接近的东西`O(n log n)`预处理，然后非常快速的查询处理。 

一些边缘情况很容易被忽略。 

考虑一个所有值都相等的数组：```
[5, 5, 5, 5]
```计算出的`mid`也是`5`，所以每个元素都进入左侧部分，右侧部分为空。 不可能进一步分裂。 唯一能达到的金额是`20`。 粗心的递归实现可能会永远递归，因为范围永远不会缩小。 

考虑：```
[1, 2]
```总金额`3`无需执行任何拆分即可实现。 一些解决方案仅记录分割后的总和，而忘记包括当前段本身。 然后查询`3`会错误地返回“否”。 

另一个微妙的情况是：```
[1, 1, 100]
```第一次分裂分开`[1,1]`和`[100]`。 可达到的金额是`102`,`2`， 和`100`。 询问`101`即使其金额介于可实现的金额之间，也必须予以拒绝。 问题不在于要求任意子集和。 只有递归分裂过程产生的和才重要。 

## 方法

 强力解释是明确遵循每个可能的选择序列。 对于每个当前数组，我们可以保留左侧部分或右侧部分，从而创建二叉递归树。 每个可达数组贡献一个可实现的总和。 

这是正确的，因为它直接匹配流程的定义。 不幸的是，表示数组并重复重新分区它们的成本很高。 在最坏的情况下，我们会重复扫描大型数组并创建许多副本。 高达`10^5`总的来说，这种方法很快就变得不切实际。 

关键的观察结果是，排序后，每个递归状态都对应于已排序数组的连续段。 

假设排序后的数组段是`a[l...r]`。 分割阈值为$$mid = \left\lfloor \frac{a[l] + a[r]}{2} \right\rfloor$$由于该段已排序，因此所有值`<= mid`形成段和所有值的前缀`> mid`形成后缀。 分割位置可以通过二分查找找到。 

现在我们不再需要跟踪实际的数组。 状态完全由索引区间描述`[l, r]`。 

每个这样的部分都有一个明确定义的总和。 在这个递归过程中出现的任何段都对应于一个可实现的数组，因此我们可以预先计算所有可实现的总和并将它们存储在一个集合中。 

一旦知道所有可实现的总和，每个查询就变成一个简单的成员资格测试。 

递归是高效的，因为每次分割都会划分值范围。 一个段只处理一次，通过二分查找来定位分割点。

 | 蛮力 | 分裂次数呈指数增长 | 指数| 太慢了 |
 | 最佳| O(n log n + q) | O(n log n + q) | O(n) | 已接受 |

 ## 算法演练

 1. 对数组进行排序。 

排序后，每次分割相当于将一个连续的段分成两个连续的子段。 
2. 构建前缀和数组。 

这允许任何段的总和`[l, r]`在常数时间内计算。 
3. 对整个排序数组段启动递归过程。 

初始段代表原始数组，其总和始终是可实现的。 
4. 对于一个段`[l, r]`，计算其总和并将其插入到集合中。 

每个递归段对应于可通过允许的操作获得的有效数组。 
5. 如果`a[l] == a[r]`， 停止。 

该段中的所有值都相同。 任何进一步的分割都会将每个元素放在同一侧，因此递归必须终止。 
6. 计算$$mid = \left\lfloor \frac{a[l] + a[r]}{2} \right\rfloor$$7. 使用二分查找查找第一个值大于的位置`mid`。 

这完全按照问题的定义确定了左组和右组之间的边界。 
8. 如果边界实际上没有分割线段，则停止。 

当一侧为空时，这可以防止无用的递归。 
9. 递归处理左边的段。 
10. 递归处理右段。 
11. 预处理完成后，通过检查其值是否存在于可实现的总和集中来回答每个查询。 

### 为什么它有效

 递归完全反映了允许的操作。 

对于任意递归段`[l, r]`，其中的值正是该过程中可能出现的某个数组的元素。 因此，分段总和是可以实现的并且必须被记录。 

反之，原流程中的每一次合法分割都会根据阈值对元素进行划分`mid`。 在排序段中，该分区正是算法使用的二分搜索分割。 递归会探索两个结果段，因此可以表示每个可能出现的数组。 

因此，由递归构建的集合包含所有可实现的和并且仅包含可实现的和。 查询应答减少为检查该集合中的成员资格。 

## Python 解决方案```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        n, q = map(int, input().split())
        a = sorted(map(int, input().split()))

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]

        possible = set()

        def dfs(l, r):
            seg_sum = pref[r + 1] - pref[l]
            possible.add(seg_sum)

            if a[l] == a[r]:
                return

            mid = (a[l] + a[r]) // 2
            p = bisect_right(a, mid, l, r + 1)

            if p == l or p == r + 1:
                return

            dfs(l, p - 1)
            dfs(p, r)

        dfs(0, n - 1)

        for _ in range(q):
            s = int(input())
            answers.append("Yes" if s in possible else "No")

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```第一步对数组进行排序，因为拆分规则仅取决于值。 一旦排序，每个递归状态就变成一个连续的索引范围。 

前缀和数组允许在恒定时间内计算段和。 如果没有它，每个递归调用都需要扫描其整个段，从而显着增加复杂性。 

这`possible`设置存储所有可实现的金额。 一旦访问了一个段，就会插入其总和，因为该段本身代表一个有效的可获取数组。 

停止条件`a[l] == a[r]`很关键。 当所有值都相等时，不存在有意义的分割。 忽略此检查可能会产生无限递归。`bisect_right`找到第一个值严格大于`mid`，完全匹配问题定义。 值等于`mid`属于左侧部分。 

支票```
if p == l or p == r + 1:
    return
```防止空分区。 这样的拆分不会减少该部分。 

最后，使用集合成员资格在恒定的预期时间内回答每个查询。

 ## 边缘情况

 ### 所有值都相同

 输入：```
1
4 2
5 5 5 5
20
10
```排序后的段有`a[l] = a[r] = 5`。 

该算法记录总和`20`并立即停止递归。 可实现的集合变为：```
{20}
```询问`20`返回“是”并查询`10`返回“否”。 这与流程相匹配，因为每次拆分都会将所有元素放入同一组中。 

### 没有任何分割的总和

 输入：```
1
2 1
1 2
3
```原始数组本身是有效的可获取数组，因为允许零操作。 

该算法在尝试任何分割之前记录根段总和，因此`3`立即插入集合中。 

答案是正确的`"Yes"`。 

### 可实现的总和之间的查询

 输入：```
1
1 4
1 1 100
101
```递归生成和：```
102, 2, 100
```没有段有总和`101`。 

算法给出答案`"No"`因为成员资格是根据可实现的总和的精确集合进行检查的，而不是根据任何间隔或子集总和标准进行检查。 

### 值等于分割阈值

 输入：```
1
3 2
2 2 3
4
3
```这里：```
mid = (2 + 3) // 2 = 2
```两次出现`2`必须属于左段。`bisect_right`查找第一个元素严格大于`2`, 生产环节`[2,2]`和`[3]`。 

可实现的金额变为：```
7, 4, 3
```查询`4`和`3`都返回`"Yes"`。 这证实了值等于`mid`都得到正确处理。
