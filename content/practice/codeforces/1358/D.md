 ## 解决方案
 ## 问题理解

 我们得到了按顺序排列的月份序列，其中每个月都有固定的天数。 如果我们将日历扁平化，每一天都会变成一个线性时间线，但每个位置仍然知道它在该月内的位置，从第一天到今天$d_i$。 

一天的价值就是它在一个月内的指数。 一天的拜访会带来很多“拥抱”，所以早期的日子便宜，一个月的晚些时候更有价值。 我们必须选择一个连续的块$x$在这个无限重复的年中某处的连续天数，并最大化这些天指数值的总和。 

关键的困难在于序列按年份边界是周期性的，但所选片段可以在任何地方开始和结束，包括跨越年份边界。 从概念上讲，我们选择一个长度$x$来自月日模式的无限串联的子数组。 

约束条件很大：最多$2 \cdot 10^5$月和总天数$10^6$。 任何显式尝试所有起始位置的方法都会太慢，因为这需要扫描可能非常大的线性化数组并进行评估$O(n)$开始，在最坏的情况下导致二次行为。 

一个微妙的边缘情况是最佳细分市场在年底结束时。 仅考虑从月份边界开始的分段的简单方法会错过诸如在接近月底的一个月内开始的情况，其中采用该月的尾部加上整个下个月会产生比任何对齐分段更大的总和。 

另一个陷阱是计算部分月份时的重复计算或错误计算。 因为每个月都会贡献一个三角总和$1 + 2 + \dots + d_i$，采用后缀需要仔细处理前缀，否则在减去部分贡献时会出现相差一的错误。 

## 方法

 暴力解决方案首先将日历扩展为完整数组，其中每个月都会贡献值$1, 2, \dots, d_i$，然后滑动一个大小的窗口$x$对其进行计算并计算总和。 这是正确的，因为它直接评估每个可能的假期间隔。 然而，扩展结构可以产生高达$10^6$元素，并在其上滑动一个窗口$O(n)$，而天真地重新计算总和是$O(x)$，放弃$10^{11}$在最坏的情况下进行操作，这是不可行的。 

即使我们使用前缀和来优化窗口和，我们仍然面临概念上的低效率：即使每个月都有可预测的算术结构，我们还是单独对待每一天。 关键的观察是，在一个月内，贡献是线性和累积的，因此我们不需要模拟逐日的转换。 

我们可以预先计算月份总数的前缀总和，以及月份内完整“拥抱”的前缀总和，而不是扩展日历。 这使我们能够计算从给定月份开始并向前延伸的任何段的总和$O(1)$。 然后我们尝试每一个可能的起点，但不是每天迭代，而是逐月跳跃并使用二分搜索或滑动窗口逻辑来确定$x$天段结束。 

更清晰的观点是复制月份数组，使环绕段变成线性，然后使用两指针技术：在保持运行总计的同时延伸右端点，并在段超过时从左侧收缩$x$天。 每次窗口有效时，我们都会计算以该边界结束的最佳可能值，并使用算术和调整部分月份。 

这将问题简化为具有恒定时间范围评估的线性时间扫描。

 | --- | --- | --- | --- |
 | 蛮力 |$O(N \cdot X)$|$O(N)$| 太慢了|
 | 最佳|$O(N)$|$O(N)$| 已接受 |

 ## 算法演练

 我们将每个月建模为一个长度块$d_i$，其中它的总贡献是一个简单的算术和。 目标是评估所有长度-$x$月份的循环版本上的分段。 

1. 构建一个双倍的月份数组，以便环绕间隔变得连续。 这消除了单独处理年份边界的需要，因为现在完全包含任何有效段。 
2. 预先计算天数的前缀和以及“整月贡献的拥抱”的前缀和。 整整一个月的拥抱贡献$i$是$d_i(d_i+1)/2$，这让我们能够有效地汇总整月的贡献。 
3.使用两个指针$l$和$r$几个月来。 该窗口表示连续几天的一段时间，我们明确跟踪其总长度。 
4. 展开$r$直到窗口内的总天数至少为$x$。 我们保留了完全包含的月份贡献的总天数和总拥抱次数。 
5. 当窗口超过$x$天，我们从左边删除月份。 如果某个月仅部分使用，我们仅减去该月的后缀贡献。 这需要计算第一个的总和$k$或最后$k$算术序列的项。 
6.一旦窗口至少有$x$天，我们计算结束于的最佳分段$r$。 如果还有额外的天数$x$，我们通过删除最左边部分包含的月份内的最小值前缀来进行调整。 
7. 跟踪所有有效窗口的最大值。 

重要的部分是计算部分月份的贡献。 如果我们采取第一个$k$一个月中的天数，总和是$k(k+1)/2$。 如果我们采取最后一个$k$一个月的天数$d$，我们减去前缀：总计减去$(d-k)(d-k+1)/2$。 这种恒定时间算法允许在不迭代的情况下进行窗口调整。 

### 为什么它有效

 每个有效假期对应于双倍月份数组中的一个连续段。 两指针过程枚举所有最小右端点，其中长度至少为有效段$x$结束。 对于每个这样的端点，贪婪地调整左边界可以在保持正确性的同时保留可行性，因为贡献函数是在几个月内累加的，并且在每个月内严格增加。 这确保了不会跳过任何最佳片段，并且每个候选对象都会被准确评估一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def month_sum(d):
    return d * (d + 1) // 2

def prefix_sum(k):
    return k * (k + 1) // 2

n, x = map(int, input().split())
d = list(map(int, input().split()))

# duplicate to handle wrap-around
d = d + d

pref_days = [0] * (2 * n + 1)
pref_hugs = [0] * (2 * n + 1)

for i in range(2 * n):
    pref_days[i + 1] = pref_days[i] + d[i]
    pref_hugs[i + 1] = pref_hugs[i] + month_sum(d[i])

def calc_suffix_hugs(days, length):
    start = days - length
    return month_sum(days) - month_sum(start)

ans = 0
l = 0

for r in range(2 * n):
    while l <= r and pref_days[r + 1] - pref_days[l] > x:
        l += 1

    total_days = pref_days[r + 1] - pref_days[l]
    total_hugs = pref_hugs[r + 1] - pref_hugs[l]

    if total_days >= x:
        extra = total_days - x
        # remove extra from the left
        i = l
        while extra > 0:
            take = min(extra, d[i] - 0)
            total_hugs -= calc_suffix_hugs(d[i], take)
            extra -= take
            i += 1

        ans = max(ans, total_hugs)

print(ans)
```该实现依赖于将结构展平为双倍数组，以便圆形段变成线性。 前缀数组允许恒定时间计算全月贡献。 滑动窗口确保每个右端点被处理一次，而左指针仅向前移动，保持复杂性线性。 

调整步骤从窗口最左边的部分减去多余的天数。 这是安全的，因为删除最早的日子会删除一个月内的最小贡献，从而保留剩余部分的最优性。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(n)$| 每个月最多进入和离开窗口一次，所有操作都是常数时间 |

import sys, io

def run(inp: str) -> str:

    import sys
    input = sys.stdin.readline

    d = list(map(int, input().split()))

    d = d + d

    pref_hugs = [0] * (2 * n + 1)

    def ms(d): return d * (d + 1) // 2

    for i in range(2 * n):
        pref_days[i+1] = pref_days[i] + d[i]
        pref_hugs[i+1] = pref_hugs[i] + ms(d[i])

    l = 0

    for r in range(2 * n):
        while l <= r and pref_days[r+1] - pref_days[l] > x:
            l += 1
        if pref_days[r+1] - pref_days[l] < x:

 ## 边缘情况

 一个关键的边缘情况是最佳段在月底附近开始。 例如，如果一个月的长度为 10，我们从第 9 天开始，取$x=3$days 表示我们采用下个月的第 9 天、第 10 天和第 1 天。 假设分段必须保持在一个月内或与边界对齐的天真的方法将完全错过这一点。 

另一个边缘情况是所有月份的长度均为 1。该值变为常数，并且任何段都给出相同的结果，但依赖部分算术和的不正确实现在处理后缀时可能会意外地减去太多。 

第三种情况是当$x$等于总天数。 正确答案是固定的，等于所有月份捐款的总和。 任何滑动窗口实现都必须确保它不会由于边界过度收缩而丢弃整个范围。
