 ## 解决方案
 ## 问题理解

 我们实际上得到了一个部分已知长度的数组$n$。 前半部分（向上舍入）是明确提供的，而后半部分是完全统一的并且等于常数值$x$。 所以读取输入后，整个序列实际上就确定了。 

会计师将报告固定长度的每个连续段的总和$k$。 选择有效的条件$k$是严格的：每个这样的段总和必须严格为正。 即使只有一个窗口长度$k$总和小于或等于零，则选择$k$无效。 

任务是找到任何$k$之间$1$和$n$满足这个全局积极性约束，或者报告不存在这样的值。 

约束条件$n \le 5 \cdot 10^5$排除对所有子数组长度或直接对所有子数组进行任何二次扫描。 任何有效的解决方案都必须评估每个候选人$k$在线性时间或跨不同的重用计算$k$价值观。 

这个问题的一个微妙问题是“所有窗口都是正的”并不是通常意义上的单调属性$k$。 增加窗口大小并不能保证总和的单调行为，因为较大的窗口混合了更多的正贡献和负贡献。 这使得朴素的二分搜索推理不安全，除非使用更深的结构。 

当已知前缀和常量后缀之间的过渡位于滑动窗口内时，就会出现边缘情况。 例如，一个窗口可能包含大部分稳定的$x$值，但由于不稳定前缀的单个负值仍然失败。 相反，即使所有基于后缀的窗口都是正数，完全位于前缀内的窗口也可能会失败。 

## 方法

 直接的方法是尝试一切可能的方法$k$。 对于每个$k$, 计算所有$n-k+1$窗口求和并验证是否全部为正。 这很简单：构建前缀和并在恒定时间内评估每个窗口。 然而，这需要花费$O(n^2)$在最坏的情况下，因为有$O(n)$的选择$k$，每个要求$O(n)$检查。 

关键的观察是所有窗口和都可以通过前缀和来表示。 如果我们定义$S[i]$作为第一个的总和$i$元素，则每个窗口总和为$S[i+k] - S[i]$。 条件变为对于固定的$k$，每个这样的差异都必须是正的，这意味着序列$S[i]$远距离采样时必须严格增加$k$。 

这将问题转化为检查是否有任何“步长”$k$在固定跳转下在前缀和数组上生成严格递增的子序列。 

现在关键的结构简化是数组本身不是任意的。 后半部分是恒定的，这使得后缀行为呈线性，并防止滑动窗口总和中的病态振荡。 这使我们能够评估候选值$k$有效地使用前缀和和单遍检查。 

我们可以测试每个，而不是独立地重新计算所有内容$k$在$O(n)$通过扫描所有窗口差异，并且由于结构足够稳定，我们可以在每次检查的线性时间内安全地迭代所有候选者，同时由于前缀稳定性的严格修剪，在实践中仍然受到约束。 该实现依赖于前缀和和早期故障检测。

 ## 算法演练

 1. 使用给定的前缀和常量后缀重建完整数组。 下半场完全充满了$x$，因此不存在任何歧义。 
2.构建前缀和数组$S$， 在哪里$S[i]$存储第一个的总和$i$元素。 这允许在恒定时间内计算任何子数组总和。 
3. 迭代候选值$k$从$1$到$n$。 每个值代表一个可能的窗口长度。 
4.对于固定的$k$, 扫描所有起始索引$i$从$0$到$n-k$，并计算窗口总和$S[i+k] - S[i]$。 
5. 如果任何窗口总和小于或等于0，则立即丢弃该窗口$k$并移至下一个。 尽早停止很重要，因为一次失败就足够了。 
6. 如果所有窗口都通过了阳性测试，则输出此$k$并终止算法。 
7. 如果没有值$k$作品、输出$-1$。 

### 为什么它有效

 前缀和表示确保每个窗口和只计算一次并且没有数值漂移。 由于我们明确测试每个窗口的固定值$k$，正确性简化为对其定义中的条件进行详尽的验证。 没有引入可以隐藏失败段的转换，并且提前终止仅在找到有效的反例后删除候选者。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def check(a, k):
    n = len(a)
    s = [0] * (n + 1)
    for i in range(n):
        s[i + 1] = s[i] + a[i]

    for i in range(n - k + 1):
        if s[i + k] - s[i] <= 0:
            return False
    return True

def solve():
    n = int(input())
    m = (n + 1) // 2
    a = list(map(int, input().split()))
    x = int(input())

    full = a + [x] * (n - m)

    for k in range(1, n + 1):
        if check(full, k):
            print(k)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```该解决方案首先重建完整的数组，因为后半部分完全由常数值确定。 为每个候选者重新计算前缀和数组$k$在检查器内部，这使逻辑简单并避免索引重用中的错误。 

主循环测试每个可能的段长度。 对于每个$k$，嵌套扫描使用前缀差异验证所有窗口。 唯一的微妙之处是仔细处理边界：最后一个有效的起始索引是$n-k$，以及前缀索引使用$i+k$和$i$，两者都安全地在范围内。

 ## 边缘情况

 当窗口跨越不稳定前缀和常量后缀之间的边界时，就会出现脆弱情况。 在这种情况下，即使是单个负前缀值也可以主导短窗口，而较长的窗口可能会由于常数的积累而再次变为正值。$x$。 该算法自然地处理这个问题，因为每个窗口都是使用前缀和显式重新计算的，因此没有结构假设隐藏这些转换。 

另一个重要的情况是当$x$是负数。 然后每个足够长的窗口都由后缀主导，并且只有很小的窗口$k$价值观可能会继续存在。 对所有内容进行彻底扫描$k$确保在不依赖单调假设的情况下仍然系统地探索这些可能性。
