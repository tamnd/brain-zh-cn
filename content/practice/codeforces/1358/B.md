 ## 解决方案

 ## 问题理解

 我们有一群老奶奶，每个人对人群规模都有自己的要求。 玛丽亚一开始独自在庭院里，并想逐渐邀请他们中的一些人。 每个奶奶都有一个门槛$a_i$，这意味着只有在她出现的那一刻，至少有$a_i$其他奶奶已经在场（将玛丽亚算作“其他人”之一）。 

关键的复杂之处在于，玛丽亚可以同时邀请多个奶奶，而他们在进入时都会看到院子的同一个快照。 因此，团体决策取决于团体的总规模与现有团体的规模相加。 

任务是确定最终可以带进来的奶奶的最大数量，因为玛丽亚可以自由选择邀请的顺序和分组。 

输入大小约束足够大，任何比每个测试用例的线性更差的解决方案都是有风险的。 高达$10^5$测试中的奶奶总数，$O(n^2)$尝试所有子集或迭代贪婪扫描的模拟会太慢。 我们的目标应该是$O(n \log n)$或更好的策略，可能涉及排序和单次传递。 

当大阈值奶奶与许多小阈值奶奶并存时，就会出现微妙的边缘情况。 例如，如果一位奶奶需要几乎全部最终人群规模，她可能会阻止天真的贪婪方法，除非她被正确推迟。 另一个极端情况是当所有值都大于$n$，在这种情况下，除了玛丽亚之外没有人可以加入，因为即使是最小的要求也无法满足。 

## 方法

 一种强力的解释是模拟邀请奶奶分组的所有可能方式。 在任何步骤中，我们都知道当前有多少个奶奶在里面，并且我们尝试剩余奶奶的子集，其约束由当前大小加上子集的大小来满足。 这很快就变成了组合：每个子集的选择都依赖于所有其他子集的选择，从而导致分组的可能性呈指数级增长。 

一种更结构化的思考方式是首先忽略分组并关注最终的排序。 如果我们能按某种顺序排列所有奶奶，那么当$k$第一个奶奶进来了，正好有$k$她之前的奶奶加上玛丽亚。 所以她看到$k$其他人（因为玛丽亚总是在场）。 这意味着条件成为对位置的限制：奶奶被放置在位置上$k$有效，如果$a_i \le k$。 

这将问题简化为选择可以排列的最大可能的奶奶前缀，以便每个位置满足其阈值。 最好的策略是首先优先考虑更容易的奶奶，即那些要求较小的奶奶，因为它们更灵活并且有助于增加前缀大小。 

排序允许我们从最小的需求向上贪婪地分配位置。 我们维护一个计数器，记录我们已经放置了多少个奶奶，如果她的要求不大于当前可实现的人群规模，我们就会将她包括在内。

 | --- | --- | --- | --- |
 | 暴力分组模拟| 指数| O(n) | 太慢了|
 | 排序+贪心赋值| O(n log n) | O(n log n) | O(1) 额外（除了输入） | 已接受 |

 ## 算法演练

 1. 对数组进行排序$a$按非递减顺序。 这确保了我们始终首先考虑最宽容的奶奶，从而最大限度地提高了容纳更多人的机会。 
2. 初始化计数器`cnt = 1`，代表玛丽亚独自在庭院里。 如果我们包括玛丽亚，这个计数器会记录当前有多少奶奶在里面。 
3. 从最小需求到最大需求遍历排序数组。 每一位奶奶$a_i$，根据当前人群规模检查她是否可以加入。 
4.如果$a_i \le cnt$，那么这位奶奶就可以安全地被包括在内。 增加`cnt`增加 1，因为我们已成功在庭院中添加了一个人。 
5. 如果$a_i > cnt$，永久跳过她。 由于数组已排序，任何后面的奶奶都会有更大或相同的要求，因此它们都不适合这个位置。 
6.处理完所有奶奶后，输出`cnt`，其中已经包括玛丽亚。 

### 为什么它有效

 在任何时刻，`cnt`代表庭院内包括玛丽亚在内的可行人数。 排序确保当我们尝试放置奶奶时，我们总是考虑剩余的最小约束。 如果奶奶不能按当前尺寸放置，那么对已经跳过的较大尺寸进行重新排列就无法在不违反之前分配的情况下使她适合。 该构造贪婪地构建最大可能的前缀，其中每个位置都满足其阈值，该阈值直接对应于最大可实现的最终组大小。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        a.sort()
        
        cnt = 1  # Maria
        
        for x in a:
            if x <= cnt:
                cnt += 1
        
        out.append(str(cnt))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```解决方案首先对需求列表进行排序，以便我们始终首先尝试满足要求最低的奶奶。 变量`cnt`追踪院子里当前的人数，从玛丽亚开始。 

当我们迭代时，每次我们发现一个奶奶的要求满足当前人群规模时，我们立即将她包括在内并增加规模。 这种贪婪的接受是安全的，因为未来的奶奶更难满足，所以推迟可行的奶奶永远不会提高可行性。 

最终值`cnt`已经包含 Maria，匹配所需的输出定义。

 ## 边缘情况

 一个关键的边缘情况是所有阈值都大于可用奶奶的数量。 例如：

 输入：```
3
10 10 10
```排序后，我们仍然有`[10, 10, 10]`。 玛丽亚开始于`cnt = 1`。 每个值都大于 1，因此没有一个值被接受，最终答案仍为 1。该算法正确地避免了尝试不可能的包含。 

另一个边缘情况是许多小值提前出现，从而产生级联效应。 例如：

 输入：```
4
1 1 1 1
```排序后的数组没有改变。 每一步都满足条件，所以`cnt`从 1 增长到 5。这表明每个接受的奶奶都严格增加容量，这就是连锁反应成功的原因。
