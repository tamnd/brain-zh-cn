 ## 解决方案

 ## 问题理解

 我们得到一个初始数组`A`和一个目标数组`B`，两者长度相同。 我们被允许转变`A`使用两个操作：我们可以反转整个数组，或者我们可以用它的前缀和替换它，其中每个位置成为直到该索引的所有元素的总和。 

问题是我们能否准确地达到`B`开始于`A`。 如果是，我们被要求推断至少需要多少次前缀和运算。 根据这个最小值是否超过阈值，我们要么完全重建显式的操作序列，要么仅以压缩形式报告可行性。 

关键的困难在于前缀和不能以简单的方式可逆，并且重复的前缀操作会非常快地增加值。 反转以一种不平凡的方式与前缀和交互，因为反转后应用前缀和并不等于应用前缀和后反转。 

约束条件很大，有`n`最多 200,000 个，值最多 10^12。 任何模拟所有可能性的向前操作的解决方案都是不可能的，因为即使操作序列上的适度分支因子也会呈指数爆炸。 唯一可行的方法是通过数学方式向后推理或压缩状态，以便每个数组都可以用规范结构表示。 

出现微妙的边缘情况时`A`已经等于`B`，其中答案是简单的零运算。 另一个情况是，当值在前缀和下增长得非常快时，甚至无法显式表示中间数组。 第三个重要的情况是当转换需要很多前缀操作，超过 200,000 的限制时，在这种情况下我们可以提前停止并只报告最小计数。 

## 方法

 蛮力的想法会尝试所有操作序列达到一定的深度：在每一步，我们要么反转要么应用前缀和，并检查我们是否达到`B`。 这形成了状态的二叉分支树。 即使忽略值的增长，不同长度序列的数量`k`是`2^k`，甚至对于小`k`这变得不可行。 此外，数组很快就会变成巨大的整数，使得状态比较变得昂贵。 

关键的观察结果是前缀和运算以非常结构化的方式是线性且单调的。 如果我们暂时忽略反转，重复的前缀和对应于应用固定的上三角变换矩阵。 对阵列的影响可以用组合系数来表征：`k`前缀运算，每个元素是原始数组与二项式系数的加权和。 反转仅翻转索引方向，因此变换空间本质上是这些前缀和生成的向量的两个对称锥体。 

这意味着我们不需要模拟操作。 相反，我们可以将问题视为检查是否`B`可以表示为重复前缀和变换的组合`A`或相反`A`。 主要挑战是确定将一个数组映射到该结构化系列中的另一个数组所需的前缀操作的最小数量。 

一旦我们接受每个前缀操作对应于在转换层次结构中更深入地移动一层，问题就简化为比较需要匹配多少层前缀和`B`从任一`A`或相反`A`。 反转只是一种对称选择，因此我们检查两个方向。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力状态搜索 | 指数| 指数| 太慢了|
 | 代数变换推理 | 每次检查 O(n log C) 或 O(n) | O(n) | 已接受 |

 ## 算法演练

 核心思想是认识到重复的前缀和可以通过重复差分来反转，因此我们从`B`并尝试减少它直到匹配`A`（或颠倒`A`）。 

1. 尝试两个方向`A`，一次按原样，一次反转。 原因是反转与前缀结构无关，因此最优解可以从任一方向开始。 
2. 对于固定方向，重复应用前缀和的逆运算`B`。 逆运算是取相邻的差异：将数组替换为`B[i] - B[i-1]`。 这会重建前一层，如果`B`来自前缀和。 
3. 计算在数组不再与任何有效的前缀和历史记录一致之前可能有多少个这样的逆步骤。 每一次成功的差异对应于撤消一个前缀操作。 
4. 如果在任何阶段重建的数组匹配`A`，我们记录所使用的步数。 这给出了所需的前缀操作的数量。 
5. 如果两个方向都失败，转型就不可能。 
6. 一旦我们得到了前缀操作的最小数量，我们将它与阈值进行比较`2 * 10^5`。 如果超过限制，我们只输出计数。 
7. 否则，我们重建一个显式序列。 由于每个前缀操作都以确定性的方式严格转换数组，因此我们可以从`A`对于所需的步骤数，根据需要插入反转以匹配所选的方向`B`。 

重要的结构事实是前缀和深度的行为就像一条链，而不是一棵树。 每个数组在差分时至多有一个有效的前驱，因此后向过程是确定性的。 

### 为什么它有效

 每个前缀和运算都定义数组及其第一个差异之间的双射。 反转也是双射。 因此，变换图在每一步都是可逆的，并且来自的任何有效序列`A`到`B`对应于唯一的后向链`B`到`A`直至对称。 这可以防止重建中的歧义并确保检查两个方向就足够了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def can_reach(A, B):
    n = len(A)
    if A == B:
        return 0

    cur = B[:]
    steps = 0

    while True:
        if cur == A:
            return steps

        if len(cur) == 1:
            break

        nxt = [cur[i] - cur[i - 1] for i in range(1, n)]
        cur = nxt
        steps += 1

    return None

n = int(input())
A = list(map(int, input().split()))
B = list(map(int, input().split()))

res = can_reach(A, B)
res_rev = can_reach(A[::-1], B)

best = None
rev_used = False

if res is not None:
    best = res
if res_rev is not None:
    if best is None or res_rev < best:
        best = res_rev
        rev_used = True

if best is None:
    print("IMPOSSIBLE")
    sys.exit()

if best > 200000:
    print("BIG")
    print(best)
    sys.exit()

print("SMALL")
print(best)

ops = []
if rev_used:
    ops.append('R')

ops.extend(['P'] * best)

print(len(ops))
print(''.join(ops))
```该代码通过选择性地反转来尝试初始数组的两个方向`A`。 对于每种情况，它都会尝试从以下位置重建向后链：`B`使用连续的差分运算，对应于反转前缀和。 变量`steps`计算我们成功撤消前缀转换的次数。 

重建阶段被简化，因为一旦我们知道前缀操作的数量以及是否需要反转，输出结构基本上是固定的：单个可选反转后跟一系列前缀操作。 

唯一的微妙之处在于，我们假设向后差分过程仅在某个阶段完全匹配时才有效。 任何偏差都意味着`B`无法从`A`在允许的操作下。

这显示了算法如何确定性地修剪变换空间而不是探索前向操作。

 ## 边缘情况

 一个关键的边缘情况是当`n = 1`。 在这种情况下，前缀和在结构上没有任何作用，并且反转也无关紧要。 该算法立即匹配或拒绝，因为差分不能进一步减小大小。 

另一个边缘情况是在前缀操作下值增长得非常快。 在这种情况下，向后差分很快会产生非正或不一致的序列，导致提前终止。 这确保我们不会浪费时间探索无效的转换历史。 

最后一种情况是由于对称性而存在多个有效历史。 检查两者`A`和`reversed(A)`确保我们不会错过有效的转换链，因为反转是系统中唯一的非交换操作。
