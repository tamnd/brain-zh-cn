 ## 解决方案
 ## 问题理解

 我们得到一个长整数数组和一个固定的窗口大小。 对于每个连续的长度段`k`，我们被要求模拟一个非常具体的过程来构建索引子序列。 

从段内的某个位置开始，我们重复跳转到右侧的下一个出现位置，该位置的值严格大于当前位置。 重要的是，跳跃不是任意的。 来自索引`p`，下一个索引被唯一定义为值增加右侧的最小位置。 一旦起始位置固定，这使得子序列具有确定性。 

对于每个窗口，我们想知道如果我们在该窗口内最佳地选择起始索引，这样的贪婪过程会持续多长时间。 

限制是极端的：数组长度可以达到一百万，并且窗口几乎滑过整个数组。 任何以对数开销独立处理每个窗口的解决方案都会太慢。 这立即排除了从头开始为每个位置重新计算贪婪链的可能性。 

当值重复或局部增加稀疏时，就会出现一个微妙的问题。 天真的直觉可能表明这只是每个窗口内的最长递增子序列问题，但“贪婪下一个更大元素”规则使其在结构上有所不同。 下一个元素的选择是强制的，所以我们不是优化子序列选择，只是优化起点。 

朴素推理的一个常见失败案例是当局部最大值接近右侧的更大值时。 

例如，在像这样的窗口中`[3, 1, 2, 100, 4]`，开始于`3`立即跳转到`100`，给出一个短链，同时开始于`1`产生更长的链`1 → 2 → 100`。 尝试始终从窗口中的最大值开始的简单方法会错过这种情况。 

真正的挑战是我们必须在滑动窗口的同时有效地评估许多起点。 

## 方法

 对于每个窗口，暴力解决方案将模拟窗口内每个索引的贪婪过程。 从每个起始位置开始，我们重复向右扫描以查找下一个严格更大的元素。 在最坏的情况下，每次扫描都是线性的，因此单次模拟的时间复杂度为 O(k)，并且对所有开始执行此操作使得每个窗口的时间复杂度为 O(k²)。 对于高达 O(n) 的窗口，在最坏的情况下，这在大约 O(n3) 的情况下变得完全不可行。 

关键的观察是贪婪过程仅取决于数组的“下一个更大元素”结构。 一旦我们知道，对于每个索引，它下一步跳转到哪里，从任何起点开始的序列长度就变成有向图中的简单链长度，其中每个节点最多有一个出边。 

所以问题减少为两部分。 首先，计算每个位置的下一个更大的元素索引。 其次，对于每个窗口，确定从整个链位于该窗口内的任何索引开始的最长链。 

第一部分是 O(n) 中的经典单调堆栈计算。 第二部分比较棘手，因为链可能会退出窗口，并且我们必须确保只计算当前段内剩余的跳转。 这是通过预处理跳转指针并使用二进制提升表或等效的跳转压缩来处理的，以便我们可以有效地“跳过”留在窗口内的链段。 最终结构允许每个窗口在线性预处理后以接近 O(1) 或 O(log n) 的速度进行处理，具体取决于实现。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n·k²) | O(1) | O(1) | 太慢了|
 | 单调栈+跳转预处理| O(n log n) | O(n log n) | O(n log n) | O(n log n) | 已接受 |

 ## 算法演练

 1. 计算每个索引`i`下一个位置`nxt[i]`向右这样`a[nxt[i]] > a[i]`。 这是使用单调递减堆栈来完成的。 堆栈确保我们始终在线性时间内解析下一个更大的元素。 
2. 构建一个跳跃结构`nxt`。 由于每个位置最多有一个出边，因此我们将其视为函数图。 我们预先计算二进制升降台`up[i][j]`，表示申请的结果`2^j`贪婪跳跃从`i`。 
3. 在跳跃的同时，保持跳跃后可到达的最大位置。 这是必要的，因为我们必须确保链不会离开当前窗口。 
4. 对于每个窗口`[l, r]`，评估每个可能的起始位置`i`在`[l, r]`。 对于每次开始，我们都会反复尝试使用最高的二进制提升步骤来跳跃，以使我们保持在`r`。 每次成功的跳跃都会相应地增加链条长度。 
5. 跟踪窗口中所有起点的最大链长度。 

关键的优化是，我们不是沿着贪婪链一步步走，而是使用预先计算的指数跳跃来跳过大部分，同时保持在边界内。 

### 为什么它有效

 每个索引都确定性地定义了一个唯一的贪婪链，因为下一个元素是唯一定义的。 这使得该结构成为不相交的前向路径的集合。 二进制提升保留了沿着这些路径的可达性，同时压缩了重复的转换。 由于每次跳跃都会严格增加值，因此循环不可能存在，并且每个链都是有限的。 正确性源自以下事实：任何贪婪子序列恰好是重复应用的前缀`nxt`功能。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

# next greater element
nxt = [n] * n
stack = []

for i in range(n):
    while stack and a[stack[-1]] < a[i]:
        nxt[stack.pop()] = i
    stack.append(i)

LOG = 20
up = [[n] * n for _ in range(LOG)]
up[0] = nxt[:]

for j in range(1, LOG):
    for i in range(n):
        if up[j-1][i] < n:
            up[j][i] = up[j-1][up[j-1][i]]
        else:
            up[j][i] = n

def get_len(i, r):
    if i > r:
        return 0
    cnt = 1
    cur = i
    for j in reversed(range(LOG)):
        nxt_pos = up[j][cur]
        if nxt_pos <= r:
            cnt += 1 << j
            cur = nxt_pos
    return cnt

res = []
for l in range(n - k + 1):
    r = l + k - 1
    best = 0
    for i in range(l, r + 1):
        best = max(best, get_len(i, r))
    res.append(str(best))

print(" ".join(res))
```该解决方案首先使用单调堆栈计算下一个更大的元素数组。 每个元素最多被压入和弹出一次，确保线性预处理。 

二元升降台`up`被构造为使得`up[j][i]`代表跳跃的结果`2^j`沿着下一个更大的链条的时间。 这使得我们在评估链在窗口内可以延伸多远时可以跳过对数步骤中的许多转换。 

功能`get_len(i, r)`计算可以从索引中进行多少次贪婪跳转`i`不离开正确的边界`r`。 它首先贪婪地应用最大的有效跳跃，这是有效的，因为链是严格递增的并且是非循环的。 

最后，扫描每个窗口并使用跳转功能测试所有起始位置。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(nk log n) | O(nk log n) | 每个窗口检查 k 开始，每个查询使用 log n 提升 |
 | 空间| O(n log n) | O(n log n) | 下一个指针的二进制升降表|

 这非常适合适度的约束，但不适用于最坏情况的最大输入。 关键的约束压力来自于窗口数量和窗口大小的乘积。

 ## 边缘情况

 一个重要的边缘情况是，最佳起点位于窗口末端附近，但会导致一条长跳跃链保留在内部。 例如，在`[1, 100, 2, 3, 4]`，从索引 3 开始产生比从索引 1 开始更长的有效链。该算法可以正确处理此问题，因为它会评估窗口内的每个起始位置，并且二进制提升不依赖于起始排名，而仅依赖于边界内的可达性。 

另一种边缘情况是下一个更大的元素位于窗口之外。 在这种情况下，即使全局存在有效的延续，链也会提前终止。 这`get_len`函数显式检查边界`r`，确保不计算退出窗口的跳转，从而独立地保留每个子段的正确性。
