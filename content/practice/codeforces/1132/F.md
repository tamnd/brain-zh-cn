 ## 解决方案
 ## 问题理解

 我们有一串小写字母。 在一次操作中，我们可以选择任何字符全部相同的连续块并将其删除。 移除后，绳子的其余部分连接在一起。 

目标是使用尽可能少的操作删除整个字符串。 

关键的困难在于删除会改变字符串的结构。 删除中间字符后，最初分开的字符可能会变得相邻。 这意味着在当地看起来不太理想的决定可能会在以后创造更好的机会。 

例如，考虑：```
abaca
```如果我们单独删除每个字符，则需要五次操作。 更好的策略是：```
abaca
delete b  -> aaca
delete both a blocks together after merging -> c
delete c
```这只需要三个操作。 

字符串的长度最多为 500。这立即排除了任何显式探索所有删除序列的方法。 可能的删除顺序的数量呈指数增长。 和$n=500$， 甚至$O(n^4)$已经有大约 625 亿次操作，而且速度太慢了。 我们需要一个动态规划解决方案$O(n^3)$。 

一些边缘情况很容易被错误处理。 

考虑：```
3
aaa
```答案是：```
1
```可以一次删除所有字符。 总是分割间隔的天真的 DP 可能会错误地产生 3。 

考虑：```
3
aba
```答案是：```
2
```删除中间的`b`，那么两个`a`字符变得相邻并且可以一起删除。 任何只查看当前相邻的相等字符的方法都会错过这种可能性。 

考虑：```
4
abab
```答案是：```
3
```相同的字母不能全部合并为单个删除。 我们必须仔细考虑中间删除后可以组合哪些字符。 

这些例子表明，问题本质上是关于间隔和未来的合并。 

## 方法

 暴力方法将递归地尝试每个有效的删除。 对于每个状态，我们选择当前可移动的统一子串之一，将其删除，然后继续。 

这是正确的，因为它探索了所有可能的操作序列。 不幸的是，生成的字符串数量呈爆炸式增长。 即使对于中等长度，状态空间也会变得巨大。 在最坏的情况下，运行时间是指数级的。 

问题的结构表明了一些不同的东西。 删除的效果仅限于间隔。 每当我们关注一个子串时$s[l..r]$，清除它的最佳方法仅取决于该间隔。 

这自然就导致了区间DP。 

让$dp[l][r]$表示删除子串所需的最少操作次数$s[l..r]$。 

假设我们要删除字符$s[l]$。 一种选择是单独删除它，然后清除其余的：$$dp[l][r] = 1 + dp[l+1][r]$$当间隔内再次出现相同的字符时，就会出现有趣的观察结果。 

如果$s[l] = s[k]$，那么删除它们之间的所有内容后，这两个相等的字符就可以参与同一个删除操作。 我们不需要对position处的角色进行额外的操作$l$。 

这给出了转换：$$dp[l][r] = \min(dp[l][r], dp[l+1][k-1] + dp[k][r])$$第一项删除匹配字符之间的所有内容。 之后，定位$l$可以与涉及位置的删除合并$k$。 

该观察将指数搜索转换为三次区间 DP。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 太慢了|
 | 最佳间隔 DP | O(n3) | O(n²) | 已接受 |

 ## 算法演练

 1. 定义`dp[l][r]`作为从索引中删除子字符串所需的最少操作数`l`索引`r`。 
2. 初始化所有单字符间隔。 

单个字符始终可以在一次操作中删除，因此：```
dp[i][i] = 1
```3. 按长度递增的顺序处理间隔。 

较小的区间必须先于较大的区间求解，因为较大的状态依赖于它们。 
4. 对于每个间隔`[l, r]`，从删除策略开始`s[l]`分别地。```
dp[l][r] = 1 + dp[l+1][r]
```这始终有效。 
5. 搜索每个位置`k`和`l < k ≤ r`这样`s[l] == s[k]`。 

中间部分消失后，可以将相同的字符一起删除。 
6. 对于每一个这样的`k`，尝试合并删除`s[l]`删除包含`s[k]`。```
cost = dp[l+1][k-1] + dp[k][r]
```第一项删除两个相等字符之间的所有内容。 第二项清除后缀，同时允许字符位于`l`加入删除字符的操作`k`。 
7. 保留所有可能性中的最小值。 
8.最终答案是`dp[0][n-1]`。 

### 为什么它有效

 DP 检查一个区间内最左边角色的所有可能的命运。 

要么单独删除该字符，其表示为`1 + dp[l+1][r]`，或者最终与其右侧某处的匹配字符一起被删除。 对于每个匹配位置`k`，必须先完全去除它们之间的间隔，这会花费`dp[l+1][k-1]`。 之后，角色位于`l`可以被吸收到与字符相同的删除操作中`k`，所以不需要额外的操作。 

每个有效的最优策略都恰好属于这些情况之一。 由于递归式在所有这些中取最小值，`dp[l][r]`等于每个区间的真实最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    dp = [[0] * n for _ in range(n)]

    for i in range(n):
        dp[i][i] = 1

    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1

            dp[l][r] = 1 + dp[l + 1][r]

            for k in range(l + 1, r + 1):
                if s[l] == s[k]:
                    middle = dp[l + 1][k - 1] if l + 1 <= k - 1 else 0
                    dp[l][r] = min(
                        dp[l][r],
                        middle + dp[k][r]
                    )

    print(dp[0][n - 1])

if __name__ == "__main__":
    solve()
```DP 表存储每个区间的答案。 单字符间隔初始化为 1，因为一次操作删除一个字符。 

通过增加长度来处理间隔。 这保证了每当我们计算`dp[l][r]`，循环中出现的所有较小间隔都已可用。 

微妙的部分是合并过渡。 什么时候`s[l] == s[k]`，我们不为位置添加额外的操作`l`。 字符位于`l`加入最终删除位置的删除`k`。 这正是递归使用的原因：```
middle + dp[k][r]
```而不是：```
middle + 1 + dp[k][r]
```另一个容易犯的错误是处理之间的空间隔`l+1`和`k-1`。 什么时候`k = l + 1`，该间隔的成本为零。 实现明确检查这种情况。 

答案存储在`dp[0][n-1]`，代表整个字符串。

 ## 边缘情况

 ### 所有字符相同

 输入：```
3
aaa
```DP首先将所有单字符间隔设置为1。计算时`[0,1]`，它注意到两端都是`a`，允许合并并将答案减少到 1。同样的情况也发生在`[0,2]`。 

最终答案：```
1
```这种情况验证了重复的相等字母被合并到一个操作中，而不是单独计数。 

### 相同的字符由另一个字符分隔

 输入：```
3
aba
```间隔`[0,2]`开始和结束于`a`。 

复发评估：```
dp[1][1] + dp[2][2]
= 1 + 1
= 2
```中间`b`首先被删除。 随后两人`a`字符变得相邻并一起消失。 

最终答案：```
2
```这正是击败仅基于当前邻接的贪婪方法的情况。 

### 没有相同的字符

 输入：```
5
abcde
```没有合并过渡适用，因为每个字符都是不同的。 

DP 反复使用：```
dp[l][r] = 1 + dp[l+1][r]
```产生：```
5
```每个字符都必须单独删除。 

### 交替模式

 输入：```
4
abab
```存在匹配对，但它们不能全部合并到单个操作中。 DP 探索每个匹配位置并发现可实现的最佳值是：```
3
```这个案例证实了递归并没有高估匹配字符的好处，并且只执行中间删除后实际上可以实现的合并。
