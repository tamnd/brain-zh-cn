 ## 解决方案
 ## 问题理解

 我们从左到右处理数组，同时保留一个值`c`， 最初`0`。 

对于每个元素`a[i]`，我们有两个选择。 我们可能会更换`c`和`c + a[i]`，或将其替换为`|c + a[i]|`。 所有元素处理完毕后，不同的选择顺序可能会产生不同的最终值`c`。 

在所有可能的过程中，令`k`是可以达到的最大最终值。 任务不是计算`k`独自的。 我们必须计算有多少不同的过程恰好达到了这个最大值。 如果两个过程在任何位置做出不同的选择，即使结果中间值恰好相等，也被认为是不同的。 

数组长度可以达到`2·10^5`，所有测试用例的长度总和是`3·10^5`。 由于每个位置都提供两种选择，因此强制执行所有程序都需要检查`2^n`州，即使对于`n = 60`，更不用说`200000`。 任何可接受的解决方案在数组大小上都必须基本上是线性的。 

棘手的部分是不同的过程可以合并为相同的值`c`。 跟踪所有可达值的简单计数 DP 很快就会爆炸，因为值可能大到`10^9 · n`。 

当两个操作产生相同的结果时，就会出现一种微妙的边缘情况。 考虑：```
a = [5]
```在唯一的一步，`c + a[i] = 5`，所以两个选择都会产生`5`。 最大值为`5`，并且有两个有效的过程，而不是一个。 任何计算状态而不是过程的解决方案都会低估。 

另一个重要的情况是在一个位置取绝对值可以在以后得到更大的结果：```
a = [-1, -2]
```如果没有绝对值，最终结果是`-3`。 在第二个位置应用操作给出`3`，这是最优的。 诸如“仅在立即有利时才取绝对值”之类的贪婪规则是不够的。 

第三种边缘情况是多个最优历史达到相同的中间值。 例如：```
a = [1, 1]
```每个操作都会使值变为非负，因此两个选择始终是等效的。 答案是`2^2 = 4`。 仅计算不同值将错误地返回`1`。 

## 方法

 最直接的解决办法就是暴力破解。 在每个位置，我们都会分为两种可能性，生成所有`2^n`程序。 对于每个过程，我们计算最终值，确定最大值，并计算有多少个过程达到该值。 

这是有效的，因为它完全遵循流程的定义。 不幸的是，对于`n = 200000`，程序数量大致为`10^60205`，这是完全不可行的。 

关键的观察是，在处理任何前缀之后，我们不需要知道每个可达值。 

假设我们已经处理了一些前缀。 让：`mn = minimum reachable value`

`mx = maximum reachable value`对于任何可达到的值`x`，下一个转换仅取决于`x + a[i]`和`|x + a[i]|`。 

功能`f(y) = y`和函数`g(y) = |y|`相对于范围端点都是单调的。 当我们在另一个步骤之后检查所有可达值时，对未来最优性唯一重要的值是最小和最大可达值。 

这导致了硬版本的标准解决方案。 首先使用仅跟踪的 DP 计算可实现的最大值：`minimum reachable value`

`maximum reachable value`对于每个前缀。 

一旦达到最大值`k`已知后，执行另一个 DP，计算有多少过程达到最佳极值状态。 

关键的事实是，与最优性相关的状态集永远不会超过每个位置的两个值：当前可达到的最小和最大值。 这使复杂性保持线性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(2^n) | O(2^n) | 太慢了 |
 | 最佳 | O(n) | 每步 O(1) 辅助 | 已接受 |

 ## 算法演练

 ### 计算最大值

 1. 从单个可达到的值开始`0`。 因此`mn = mx = 0`。 
2. 对于每个元素`a[i]`，计算从当前极值可获得的所有值：`mn + a[i]`

`mx + a[i]`

`|mn + a[i]|`

`|mx + a[i]|`3. 新的最小可达值是这四个数字中的最小值。 
4. 新的最大可达值是这四个数字中的最大值。 
5. 处理完整个数组后，最终可达到的最大值为`mx`。 

不明显的部分是为什么四个端点转换就足够了。 每一步之后的可达集根据可达极值形成一个区间，并且两个转移操作都在区间端点处达到其极值。 

### 计算最佳程序

 1. 重新计算每个前缀的极值 DP 数组。 
2.让`mn[i]`和`mx[i]`表示处理第一个后可达到的最小和最大值`i`元素。 
3. 维护达到这些极值的过程的计数。 
4. 对于每个位置，尝试从之前的极值状态开始的所有转换：

 使用这两种操作从先前的最小值开始，

 使用这两种操作从先前的最大值。 
5. 每当转换产生新的最小值时，将其计数添加到最小计数器。 
6. 每当转换产生新的最大值时，将其计数添加到最大计数器。 
7. 如果最小值和最大值重合，请仔细合并计数，以避免对同一状态进行重复计算。 
8. 处理完所有位置后，输出与最终最大值相关的计数。 

所有计数均以模数进行`998244353`。 

### 为什么它有效

 对于每个前缀，每个可达值都位于前缀最小值和前缀最大值之间。 将任一操作应用于该间隔内的值都无法创建不是从间隔端点之一获取的新最小值或最大值。 

因此，未来的最优行为仅取决于两个极值状态。 第一个 DP 正确计算每个前缀后的极值可达值。 第二个 DP 传播实现这些极值的过程数量。 由于每个最优最终过程都必须以全局最大可达值结束，因此计算每一步达到极值状态的方式就可以准确计算达到最终最优值的过程。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        mn = [0] * (n + 1)
        mx = [0] * (n + 1)

        for i in range(1, n + 1):
            x = a[i - 1]

            vals = (
                mn[i - 1] + x,
                mx[i - 1] + x,
                abs(mn[i - 1] + x),
                abs(mx[i - 1] + x),
            )

            mn[i] = min(vals)
            mx[i] = max(vals)

        if mn[0] == mx[0]:
            cnt_mn = 1
            cnt_mx = 1
        else:
            cnt_mn = 1
            cnt_mx = 1

        cur_mn = 0
        cur_mx = 0

        for i in range(1, n + 1):
            x = a[i - 1]

            nmn = mn[i]
            nmx = mx[i]

            next_cnt_mn = 0
            next_cnt_mx = 0

            states = []

            if cur_mn == cur_mx:
                states.append((cur_mn, cnt_mx))
            else:
                states.append((cur_mn, cnt_mn))
                states.append((cur_mx, cnt_mx))

            for value, ways in states:
                y1 = value + x
                y2 = abs(y1)

                if y1 == nmn:
                    next_cnt_mn = (next_cnt_mn + ways) % MOD
                if y1 == nmx:
                    next_cnt_mx = (next_cnt_mx + ways) % MOD

                if y2 == nmn:
                    next_cnt_mn = (next_cnt_mn + ways) % MOD
                if y2 == nmx:
                    next_cnt_mx = (next_cnt_mx + ways) % MOD

            cur_mn = nmn
            cur_mx = nmx
            cnt_mn = next_cnt_mn
            cnt_mx = next_cnt_mx

        print(cnt_mx % MOD)

if __name__ == "__main__":
    solve()
```第一个循环计算每个前缀后的最小和最大可达值。 仅需要四个候选值，因为转换后的每个极值都必须来自先前的极值。 

第二个循环执行计数。 对于每个极端状态，我们都会尝试两种合法操作。 每当转换达到下一个前缀最小值或最大值时，我们就会添加相应数量的过程。 

特殊处理时`cur_mn == cur_mx`是必不可少的。 在这种情况下，只有一个实际状态，即使它同时代表两个极值。 处理两次会重复计算程序。 

所有算术都使用模`998244353`，根据需要。

 ## 边缘情况

 考虑：```
n = 2
a = [1, 1]
```第一步之后，两个操作都会产生`1`。 在第二步之后，两个操作都会产生`2`。 有四种不同的程序：```
(+,+)
(+,abs)
(abs,+)
(abs,abs)
```该算法计算的是转换而不是不同的值，因此它会正确返回`4`。 

考虑：```
n = 2
a = [-1, -1]
```第一步之后可达到的极值是`-1`和`1`。 处理第二个元素表明只有一个历史达到最佳最终值。 计数 DP 对最小和最大极值状态进行单独计数并正确输出`1`。 

考虑：```
n = 2
a = [0, 0]
```两个操作总是产生相同的值。 尽管每个状态值都是相同的，但问题计算的是过程，而不是结果值。 该算法分别添加两个操作的贡献，产生`2^2 = 4`，这是正确答案。
