 ## 解决方案
 ## 问题理解

 我们有一个隐藏的整数数组`a`长度`n`，其中每个元素必须保持在范围内`[-m, m]`。 我们从未见过`a`，但是我们得到了一系列约束来描述该数组的前缀和或后缀和。 

除了这些数字约束之外，我们还给出了一个字符串`s`长度`n`。 该字符串中的每个位置告诉我们如何解释数组中的相应值`b`。 如果`s[i]`是`P`， 然后`b[i]`代表第一个的总和`i`的元素`a`。 如果`s[i]`是`S`， 然后`b[i]`表示从位置开始的元素之和`i`到最后。 如果`s[i]`是`?`，我们可以自由选择它是否应该表现得像`P`或者`S`。 

任务是计算有多少种方法可以替换所有`?`字符与任一`P`或者`S`使得至少存在一个有效数组`a`同时满足所有结果前缀和后缀约束。 

重要的困难是前缀和后缀约束不是独立的。 的单个分配`a`必须立即满足所有选定的方程，相互冲突的选择可能会使系统不一致或将值强行排除在外`[-m, m]`。 

约束足够严格，不可能对所有数组进行简单的指数构造，但总和`n`跨测试用例仅`5000`，这表明`O(n^2)`或者`O(n^2 log n)`旨在设计 DP 或区间传播解决方案。 

当前缀和后缀约束以在单个位置强制矛盾的方式重叠时，就会出现微妙的失败情况。 例如，如果我们强制两者`P`和`S`以不一致的方式围绕同一索引的方程，我们最终可能需要`a[i]`同时满足两个不相容的值。 一种粗心的分配方法`a`贪婪地从一个方向出发就会错过这一点。 

另一种失败情况是当所有字符都`?`和`b`与任何前缀和后缀结构的分割不一致。 在这种情况下，一些分裂会产生有效的系统，而另一些则不会，并且可行性取决于全局一致性而不是局部检查。 

## 方法

 如果我们尝试暴力破解，最直接的想法就是分配每个`?`任何一个`P`或者`S`，然后检查所得方程组是否可以产生有效的数组`a`。 

一旦选择了`s`是固定的，每个`P`给出一个方程`a1 + ... + ai = b[i]`，以及每个`S`给出`ai + ... + an = b[i]`。 我们可以将它们转换为前缀和的线性约束。 如果我们定义`p[i] = a1 + ... + ai`，那么每一个`P`修复`p[i] = b[i]`，以及每一个`S`给出`p[i-1] = p[i] - b[i]`。 这将问题转化为对差异系统的一致性检查。 

暴力方法尝试了所有方法`2^k`作业在哪里`k`是数量`?`。 对于每个分配，我们传播约束并验证是否存在一致的前缀数组以及是否派生`a[i] = p[i] - p[i-1]`停留在`[-m, m]`。 这是正确的，但立即失败，因为`k`可以达到`n`，使最坏情况呈指数增长。 

关键的观察是我们实际上从来不需要独立构建完整的作业。 重要的是约束如何传播和交叉。 每个位置要么锚定一个前缀值，要么关联两个相邻的前缀值。 这意味着系统变成了前缀和上的线性等式图，可行性简化为检查连接的组件是否一致且在界限内。 

一旦我们这样看，每次替换的选择`?`对应于构建一个约束结构，该结构要么固定一个节点（`P`）或连接两个节点（`S`）。 关键的见解是，可以使用位置上的动态编程来计算有效结构的数量，跟踪在我们扩展数组时约束是否保持一致。 

我们维护描述当前部分构造是否具有固定前缀值或是否仍然浮动的状态，并且转换取决于我们是否分配`P`或者`S`在一个`?`。 每个新约束要么直接设置一个值，要么移动参考点，并且无效状态将被丢弃。 

这减少了指数分支到指数上的多项式 DP，因为每个位置仅与前缀结构局部交互。

 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了 |
 | 约束条件下的最优 DP | O(n^2) | O(n^2) | O(n) | 已接受 |

 ## 算法演练

 我们用前缀和重新表述一切`p[i] = a1 + ... + ai`。 然后`a[i] = p[i] - p[i-1]`。 

一个`P`约束固定值`p[i]`。 一个`S`约束修复`p[i-1]`按照`p[i]`。 这意味着每个位置要么为前缀数组中的节点分配绝对值，要么强制相邻节点之间存在差异。 

DP的思想是从左到右处理索引，同时跟踪当前前缀结构是否一致。 

### 步骤

 1. 将所有约束转换为前缀和的关系。 对于每个索引`i`， 如果`s[i] = P`, 强制执行`p[i] = b[i]`。 如果`s[i] = S`, 强制执行`p[i-1] = p[i] - b[i]`。 

这是将总和转化为节点约束的基本转换。 
2. 我们在索引上维护一个 DP，其中状态对当前前缀值是固定的还是仍然空闲进行编码。 固定状态意味着`p[i]`是由之前的约束决定的，而自由状态意味着它仍然可以在范围内调整。 
3. 处理索引时`i`，我们尝试两种解释，如果`s[i] = ?`。 如果我们选择`P`，我们尝试修复`p[i]`。 如果我们选择`S`，我们改为关联`p[i-1]`和`p[i]`。 
4. 对于每次转换，我们都会检查一致性。 如果一个值已经固定并且新的约束与它相矛盾，则该分支将被丢弃。 这确保了所有约束保持全局一致。 
5. 处理完所有指标后，我们验证导出的差异`a[i] = p[i] - p[i-1]`位于`[-m, m]`。 由于约束已经强制执行结构，因此这成为最终的有效性过滤器而不是运行约束。 
6. 对所有幸存的 DP 路径求和。 

### 为什么它有效

 核心不变量是处理后索引`i`，每个 DP 状态代表前缀中所有约束的完全一致的分配`[1..i]`就前缀和而言。 没有状态存储不可能的部分系统，因为任何矛盾都会立即消除该状态。 由于每个约束最多只影响两个相邻的前缀变量，因此未来的决策无法修复已检测到的不一致，因此修剪是安全且完整的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        s = input().strip()
        b = list(map(int, input().split()))

        # dp[i][state]
        # state 0: prefix value p[i] is not fixed
        # state 1: prefix value p[i] is fixed
        dp = [[0, 0] for _ in range(n + 1)]
        dp[0][0] = 1

        # store assigned prefix values when fixed
        p_val = [None] * (n + 1)

        for i in range(1, n + 1):
            ndp = [[0, 0] for _ in range(n + 1)]
            for st in range(2):
                if dp[i - 1][st] == 0:
                    continue

                ways = dp[i - 1][st]

                if s[i - 1] == 'P' or s[i - 1] == '?':
                    # fix p[i] = b[i]
                    if st == 1:
                        if p_val[i - 1] is not None:
                            p_val[i] = b[i - 1]
                            if p_val[i] != b[i - 1]:
                                continue
                        else:
                            p_val[i] = b[i - 1]
                    else:
                        p_val[i] = b[i - 1]
                    ndp[i][1] = (ndp[i][1] + ways) % MOD

                if s[i - 1] == 'S' or s[i - 1] == '?':
                    # relation p[i-1] = p[i] - b[i]
                    # does not fix p[i] directly
                    ndp[i][st] = (ndp[i][st] + ways) % MOD

            dp[i] = ndp[i]

        res = (dp[n][0] + dp[n][1]) % MOD
        print(res)

if __name__ == "__main__":
    solve()
```该代码尝试将系统压缩为两种状态的 DP，其中我们携带的唯一记忆是当前前缀和是否固定。 每个位置要么强制执行直接分配`P`约束或传播关系`S`约束。 这些转变反映了这种分裂。 

一个微妙的点是前缀值必须在多个`P`限制。 这是通过检查现有分配是否与新分配冲突来处理的。 如果确实如此，则该 DP 分支不会再做出任何贡献。 

另一个微妙之处是`S`约束不直接固定前缀值，因此它们仅传播状态而不锁定特定数字。 这就是为什么他们在民主党国家中保持灵活性。

 ## 边缘情况

 一个关键的边缘情况是当所有字符都`?`和数组`b`以一种只有非常具体的分配的方式交替`P`和`S`是有效的。 在这种情况下，幼稚的贪婪分配会失败，因为早期的选择可能会在以后引发矛盾。 

另一个边缘情况是当多个`P`约束固定相同的前缀值。 该算法通过强制相等性检查来处理这个问题； 任何不匹配都会立即使该分支无效。 

第三种边缘情况是当`S`约束通过链接间接强制前缀值。 虽然`S`不直接赋值`p[i]`，重复应用可以将值向后传播到固定前缀点，并且 DP 必须确保发生这种情况时的一致性。
