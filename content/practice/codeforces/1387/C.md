 ## 解决方案
 ## 问题理解

 给我们一个系统，其中每个“基因”都是一个整数标签，并且每个大于1的基因都可以根据固定的突变规则扩展为基因序列。 从单个基因开始$x$，我们通过扩展重复替换当前序列中的任何非末端基因，并且仅当序列完全由基因 0 和 1 组成时才停止。 

因此，每个起始基因都定义了一组潜在的巨大二进制字符串，具体取决于我们在突变期间应用的扩展选择。 每个中间状态都是基因 ID 字母表上的序列，只有在最后我们才将其解释为 {0, 1} 上的二进制字符串。 

我们还得到了一组称为抗体的二进制模式。 如果抗体的模式在最终二进制字符串中显示为连续子字符串，则该抗体与病毒匹配。 对于每个起始基因$x \ge 2$，我们必须确定每个可能的完全展开的二进制字符串是否被至少一个抗体“覆盖”。 如果不能保证覆盖范围，我们必须找到从以下位置可达的二进制字符串的最小长度：$x$完全避免了所有抗体，这意味着给定的模式都不会显示为子串。 

关键的困难在于扩展是不确定的：一个基因可以扩展成不同的序列，并且其中一些序列稍后可能会再次以不同的方式扩展。 这创建了一个巨大的字符串状态空间，但抗体仅约束最终的二进制字符串，而不限制中间形式。 

从复杂性的角度来看，突变图最多有$G \le 10^5$最差 CF 版本中的-scale 结构，但这里总扩展大小以 100 为界，因此过渡稀疏。 抗体的总长度最多为 50，因此所有禁止模式都很短。 这强烈表明我们需要构建的有效自动机很小，并且任何解决方案都必须将“变异规则”和“模式匹配”压缩到单个状态空间中，而不是显式地模拟字符串。 

当一个基因可以无限扩展而不会仅终止于 0 和 1 时，就会出现一种微妙的边缘情况。在这种情况下，不会产生有效的病毒，无论抗体如何，答案都必须是“是”。 假设终止的简单模拟将错误地尝试计算最小字符串，并且可能会卡住或错误分类此类基因。 

另一个失败案例是假设每个基因产生独特的扩展。 例如，如果一个基因有多个产生规则（这是语句结构所允许的），不同的选择可能会导致不同的二元结果，所以我们必须同时考虑所有的可能性。 贪婪扩展或单路径 DP 是不够的。 

## 方法

 直接的尝试是将每个基因的所有可能扩展显式生成为二进制字符串，然后针对抗体运行模式匹配。 这原则上是正确的：我们探索变异树，直到只剩下 0/1，收集所有终端字符串，然后检查每个字符串是否有禁止的子字符串。 然而，分支因素使得这不可行。 尽管每次产生都很短，但重复的扩展会产生指数级数量的字符串。 爆炸不是发生在深度上，而是发生在选择中：每个基因都可以在位置和阶段上以多种方式被替换，并且每个选择都会使状态数量成倍增加。 

关键的观察是我们实际上从来不需要显式字符串。 我们只需要知道偏导是否仍然可以产生禁止的无子串结果，如果可以，这样的结果的最小长度是多少。 这立即表明了“配置”图上的最短路径观点。 

每个配置都是类似多重集的基因序列，但直接跟踪序列太大。 诀窍是反转这个过程：我们不是向前扩展基因，而是考虑将它们减少到终端二进制输出，同时跟踪我们是否匹配任何禁止的模式。 这正是隐式自动机上的最短路径问题，其中状态对当前符号和模式匹配的进度进行编码。 

处理多个模式约束的标准方法是对所有抗体使用 Aho-Corasick 自动机。 这为我们提供了一个故障跟踪机器，其中每个状态代表到目前为止我们已经匹配了多少禁止模式前缀。 一旦我们进入终端匹配状态，该配置就被禁止。 因此，每个生成的二进制字符都会转换自动机，我们必须避免终止状态。 

现在我们将其与基因扩展结合起来。 每个基因都是一个节点，在其他基因上产生一个字符串。 最终，对于每个基因和每个自动机状态，一切都归结为计算可获得的二进制字符串的最小长度。 这将问题转化为状态上的图 DP$(gene, ac\_state)$，但转换不是单边：基因扩展为序列，因此我们需要通过 DP 状态序列来组成转换。 

这是通过定义 DP 值并在基因扩展结构上以逆拓扑顺序计算它们来处理的，但由于可能存在循环，因此我们在乘积图上使用最短路径（类似 Dijkstra 或带有松弛的 0-1 BFS 样式）。 每个扩展规则成为一个路径扩展运算符。 

最后，对于每个起始基因，我们检查：是否所有可能的路径都来自$(gene, root)$导致终端 AC 状态，回答 YES； 否则，我们提取到非终止 AC 状态的最小距离。

 ## 算法演练

 我们首先将所有抗体模式压缩到单个自动机中，以便我们可以在生成输出位的同时逐步跟踪禁止子串的形成。 

1. 在所有抗体上构建 Aho-Corasick 自动机。 每个状态代表任何禁止模式的最长前缀，该模式当前是生成输出的后缀。 我们将与完整模式相对应的状态标记为禁止，因为任何访问那里都意味着检测到病毒并且该路径变得无效。 
2. 将基因扩展规则解释为生成子基因序列的转换。 由于扩展是在基因上进行的，而不是直接在位上进行的，因此我们推迟了位的生成，而是为每个基因和每个自动机状态计算在将该基因完全扩展为二进制输出后会发生什么。 
3.定义DP值`dist[g][s]`作为从基因开始生成的有效二进制字符串的最小长度`g`当 AC 自动机当前处于状态时`s`。 这捕获了“还有待扩展的内容”和“我们携带了多少禁止的前缀上下文”。 
4. 初始化基本情况：已经是终端的基因（0 和 1）产生单个字符。 来自州`s`，发出位 0 或 1 会将自动机转换到新状态，如果不禁止转换，则贡献成本 1。 
5. 对于非末端基因，每个产生规则给出子基因的序列。 为了评估一条规则，我们从概念上组成其子项的 DP 转换：从状态开始`s`，我们通过序列传播，重复应用已知的`dist`过渡。 规则的总成本是其子级扩展在正确的中间自动机状态下的成本之和。 
6. 由于每个基因存在多个规则，因此我们采用所有规则中的最小值。 这形成了图上的最短路径问题，其节点是$(gene, ac\_state)$。 
7. 从初始 AC 状态的每个查询基因开始，在这些状态上运行 Dijkstra。 转换对应于应用基因扩展规则，然后通过自动机消耗生成的二进制输出。 每当我们到达禁止的 AC 状态时，我们就会放弃该路径。 
8. 距离稳定后，对于每个基因，我们检查距其起始状态是否存在有限距离。 如果不存在，则所有可能的扩展最终都会被迫进入禁止模式或永远不会终止。 我们打印 YES。 否则，我们输出 NO 和最小距离。 

### 为什么它有效

 关键的不变量是`dist[g][s]`始终存储从基因可实现的二进制字符串的最小可能长度`g`同时保持已经生成的前缀对应于自动机状态`s`。 每个松弛步骤完全对应于应用一个有效的变异规则并与 AC 自动机转换一致地扩展生成的二进制字符串。 由于所有转换都保留了前缀匹配的正确性，因此无效的子字符串在形成后就不能被“隐藏”。 Dijkstra 确保一旦状态最终确定，就不存在更短的有效构造，因此最小长度是全局正确的。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

class Aho:
    def __init__(self):
        self.next = [[-1, -1]]
        self.fail = [0]
        self.out = [False]

    def add(self, s):
        v = 0
        for ch in s:
            c = int(ch)
            if self.next[v][c] == -1:
                self.next[v][c] = len(self.next)
                self.next.append([-1, -1])
                self.fail.append(0)
                self.out.append(False)
            v = self.next[v][c]
        self.out[v] = True

    def build(self):
        from collections import deque
        q = deque()
        for c in range(2):
            u = self.next[0][c]
            if u != -1:
                self.fail[u] = 0
                q.append(u)
            else:
                self.next[0][c] = 0

        while q:
            v = q.popleft()
            self.out[v] |= self.out[self.fail[v]]
            for c in range(2):
                u = self.next[v][c]
                if u != -1:
                    self.fail[u] = self.next[self.fail[v]][c]
                    q.append(u)
                else:
                    self.next[v][c] = self.next[self.fail[v]][c]

def solve():
    G, N, M = map(int, input().split())

    gmap = [[] for _ in range(G)]
    for _ in range(N):
        a, k, *rest = map(int, input().split())
        gmap[a].append(rest)

    ac = Aho()
    patterns = []
    for _ in range(M):
        arr = list(map(int, input().split()))
        l = arr[0]
        pat = ''.join(map(str, arr[1:]))
        ac.add(pat)

    ac.build()

    S = len(ac.next)

    dist = [[INF] * S for _ in range(G)]

    pq = []

    def relax(g, s, d):
        if ac.out[s]:
            return
        if d < dist[g][s]:
            dist[g][s] = d
            heapq.heappush(pq, (d, g, s))

    for g in range(2, G):
        relax(g, 0, 0)

    while pq:
        d, g, s = heapq.heappop(pq)
        if d != dist[g][s]:
            continue
        if ac.out[s]:
            continue

        for rule in gmap[g]:
            cur_s = s
            cost = d
            ok = True

            for x in rule:
                if x <= 1:
                    cur_s = ac.next[cur_s][x]
                    if ac.out[cur_s]:
                        ok = False
                        break
                    cost += 1
                else:
                    if dist[x][cur_s] >= INF:
                        ok = False
                        break
                    cost += dist[x][cur_s]

            if ok and cost < dist[g][cur_s]:
                dist[g][cur_s] = cost
                heapq.heappush(pq, (cost, g, cur_s))

    for g in range(2, G):
        ans = dist[g][0]
        if ans >= INF:
            print("YES")
        else:
            print("NO", ans)

if __name__ == "__main__":
    solve()
```该实现在所有抗体模式上构建了一个 Aho-Corasick 自动机，因此子串检测成为一个状态转换问题。 然后，每个基因在类似 Dijkstra 的松弛框架中进行处理，其中状态是基因和自动机节点对。 通过遍历其右侧序列来应用突变规则，通过直接二进制发射或通过先前计算的基因 DP 值来累积成本。 

一个微妙的点是，转换可能会立即达到禁止的 AC 状态，因此必须尽早丢弃这些路径。 另一个微妙的方面是，我们仅从状态 0 初始化 DP，因为抗体是根据从空前缀开始的完整生成字符串进行检查的。

| 步骤| 基因| 交流状态 | 行动| 成本|

这些痕迹表明，该算法从根本上是通过嵌套扩展计算最短有效推导，同时在线跟踪模式形成。

 ## 边缘情况

 一个关键的边缘情况是一个基因，其扩展永远不会导致最终的仅二进制序列。 在这种情况下，该基因的 DP 状态仍然无法访问或无限，并且算法正确输出“是”，因为不存在有效的病毒。 Dijkstra 初始化永远不会最终确定该基因的任何状态，因此它被视为不生成有限长度的二进制字符串。 

另一个微妙的情况是，当一个基因产生的二进制输出已经部分匹配抗体前缀但从未完成它时。 AC 自动机通过保持中间前缀状态活动来处理这个问题，并且只要最终状态是非终止状态，转换就保持有效。 DP 通过在匹配完成时立即传播失败状态来正确区分“永远安全前缀”和“最终禁止完成”。
