 ## 解决方案
 ## 问题理解

 机器人从一个整数点 (x 1 ​ ,y 1 ​ ) 开始，并且必须到达另一个整数点 (x 2 ​ ,y 2 ​ )。 有两个固定无线电塔，分别位于 (0,0) 和 (1,0)。 每个命令都会将当前点围绕这些塔之一顺时针或逆时针旋转 90 ∘。 因此，这四个命令是平面的四个仿射变换。 任务是打印最多 10 6 个执行所需转换的命令，或者打印`-1`当目的地无法到达时。 

官方限制将每个坐标设置在-100000到100000之间，而命令限制为10 6，时间限制为2秒，内存为512 MB。 明确搜索平面大部分的解决方案没有吸引力。 有用的构造必须避免依赖于所探索的坐标区域的大小，并且应该在坐标差中以大致线性的时间产生序列。 

第一个隐藏属性是奇偶性。 每个操作都保留 x+y 的奇偶校验。 例如，命令1将(x,y)变换为(y,−x)，其坐标和为y−x，与x+y具有相同的奇偶性。 绕 (1,0) 旋转的行为类似。 因此，诸如 (0,1) 之类的点无法达到 (1,1)，因为它们的和具有不同的奇偶性。 这正是第二个官方样品。 

另一种容易处理不当的情况是仅沿一条对角线的位移。 从(0,0)到(1,1)，位移为(1,1)，所以构造只需要命令`23`。 假设两个对角线分量均为正或负的通用实现在这里会失败，因为两个计数之一为零。 

第三种边界情况是大位移。 从(−100000,−100000)到(100000,100000)，位移为(200000,200000)。 该建筑使用了20万份对角线平移`23`，对于 400000 个命令，远低于 10 6。每单位曼哈顿距离执行一个命令的解决方案在这里仍然可以工作，但是通过命令序列进行强力搜索将是完全不可行的。 

最后，该声明保证起点和终点不同。 因此，诸如 (5,5) 到 (5,5) 之类的输入位于有效输入域之外，即使在数学上空序列可以解决它。 程序不需要生成空命令序列。 

## 方法

 一种直接的方法是将每个整数点视为图顶点，并将每个点连接到四个命令获得的四个位置。 广度优先搜索是正确的，因为每个命令都有单位成本，因此 BFS 第一次到达目标时它就找到了有效的序列。 问题在于图表的大小。 在输入允许的坐标方块内，大约有 200001 2 个或大约 4⋅10 10 个可能的点。 即使检查每个这样的点的四个传出转换也需要大约 1.6⋅10 11 次转换检查。 直接搜索命令字符串更糟糕：所有长度至多为 L 的字符串都包含 (4 L+1 -1)/3 种可能性。 

蛮力方法之所以有效，是因为每个命令都可以被精确模拟，但它会失败，因为它忽略了四个变换共享的代数结构。 关键的观察是两个命令可以取消旋转并留下纯平移。 

令命令1绕(0,0)顺时针旋转，命令4绕(1,0)逆时针旋转。 应用命令 1，然后应用命令 4 给出

 (x,y) 1 ​ (y,−x) 4 ​ (1+x,y−1)。 

所以这一对`14`将每个点平移 (1,−1)。 

同样，命令 2 后跟命令 3 给出

 (x,y) 2 ​ (−y,x) 3 ​ (1+x,1+y),

 所以`23`将每个点平移 (1,1)。 

这两个转换构成了可到达的奇偶校验类的基础。 如果需要的位移是

 (dx,dy)=(x 2 ​ −x 1 ​ ,y 2 ​ −y 1 ​ ),

 我们可以把它写成

 (dx,dy)=a(1,1)+b(1,−1),

 哪里

 a= 2 dx+dy ​ ,b= 2 dx−dy ​ .

 当 dx 和 dy 具有相同奇偶校验时，这些值恰好是整数，相当于 x 1 ​ +y 1 ​ 和 x 2 ​ +y 2 ​ 具有相同奇偶校验。 

负翻译是通过反转相应的两个命令序列来获得的。 的逆`23`是`41`，产生 (−1,−1)，以及其逆`14`是`32`，产生(−1,+1)。 

命令数量特别方便。 我们需要 2(∣a∣+∣b∣) 个命令，并且

 ∣a∣+∣b∣=max(∣dx∣,∣dy∣)。 

由于每个坐标差最多为 200000，因此最终序列最多包含 400000 个命令，远低于允许的 10 6。

 ## 算法演练

 1. 计算位移 dx=x 2 ​ −x 1 ​ 和 dy=y 2 ​ −y 1 ​。 整个结构只需要重现这种位移，因为我们使用的命令对是从每个起点都以相同方式工作的翻译。 
2. 检查 x 1 ​ +y 1 ​ 和 x 2 ​ +y 2 ​ 奇偶校验是否相同。 如果不同，则打印`-1`。 每个合法命令都保留 x+y 的奇偶校验，因此任何序列都不能在两个奇偶校验类别之间交叉。 
3. 计算

 a=(dx+dy)/2,b=(dx−dy)/2。 

值a告诉我们应用平移(1,1)多少次，而b告诉我们应用(1,−1)多少次。 奇偶校验保证两个划分都是准确的。 
4. 对于 a>0 的每个单位，附加`23`。 每对都将 (1,1) 添加到当前位置。 对于<0，附加`41`相反，因为该对相加 (−1,−1)。 
5. 对于 b>0 的每个单位，附加`14`。 每对相加 (1,−1)。 对于 b<0，附加`32`，它加上 (−1,1)。 
6. 打印结果序列。 由于 2(∣a∣+∣b∣)=2max(∣dx∣,∣dy∣)≤400000，自动满足命令限制。 

### 为什么它有效

 不变量是 x+y 的奇偶校验，因此奇偶校验测试消除了每个无法到达的目标。 对于可到达的目标，两个坐标中的位移具有相同的奇偶性，这使得 a 和 b 为整数。 命令对`23`和`14`是 (1,1) 和 (1,−1) 的平移，而`41`和`32`是它们各自的倒数。 因此，生成的序列将起点精确地改变了 a(1,1)+b(1,−1)=(dx,dy)，将机器人放置在 (x 2 ​ ,y 2 ​ ) 处。 

## Python 解决方案```python
Pythonimport sysinput = sys.stdin.readline

def solve():    x1, y1 = map(int, input().split())    x2, y2 = map(int, input().split())
    # x + y parity is invariant under every command.    if (x1 + y1) % 2 != (x2 + y2) % 2:        print(-1)        return
    dx = x2 - x1    dy = y2 - y1
    # dx = a + b    # dy = a - b    a = (dx + dy) // 2    b = (dx - dy) // 2
    ans = []
    if a > 0:        ans.append("23" * a)    elif a < 0:        ans.append("41" * (-a))
    if b > 0:        ans.append("14" * b)    elif b < 0:        ans.append("32" * (-b))
    s = "".join(ans)
    print(len(s))
```第一个检查仅使用奇偶校验，因此不涉及浮点运算。 这比在使用后检查下面的两个除法是否恰好产生整数更好`/`。 

变量`a`和`b`直接来自求解两个方程 a+b=dx 和 a−b=dy。 Python 的整数除法在这里是安全的，因为奇偶校验条件已经建立了可被 2 整除的能力。 

该序列作为字符串累积，而不是将每个单独的命令存储为单独的 Python 对象。 最大的有效答案有 400000 个字符，因此产生的内存占用很小。 

两个翻译组的顺序并不重要，因为都是普通翻译。 全部应用`23`或者`41`首先配对`14`或者`32`之后的对恰好产生它们的位移向量的总和。 

Python整数不会溢出，并且此构造中的最大中间坐标仅约为给定坐标范围加上生成的位移。

## 边缘情况

 ### 奇偶校验不匹配

 考虑```
0 11 1
```初始和为 1，目标和为 2。由于每个命令都保留 x+y 的奇偶校验，因此算法立即打印`-1`。 仅检查坐标在几何上是否接近的结构可能会错误地尝试生成命令。 

### 一个对角线系数为零

 对于```
0 01 1
```我们得到 dx=1，dy=1，所以 a=1，b=0。 该算法发出`23`。 命令 2 将 (0,0) 映射到自身，命令 3 将其映射到 (1,1)。 除了避免不必要的重复之外，不需要对零系数进行特殊处理。 

### 负系数

 对于```
10 10-10 -10
```我们得到 a=−20 和 b=0。 该算法发出`41`二十次。 每个`41`将点平移 (−1,−1)，因此重复 20 次后总位移为 (−20,−20)，正是所需的变化。 

### 最大位移

 对于```
-100000 -100000100000 100000
```我们有 a=200000 和 b=0。 该序列由 200000 个副本组成`23`，发出 400000 个命令。 10 6 的界限还没有被超过，因此不需要更复杂的压缩方案。 

### 尽管距离很短，但奇偶校验错误

 对于```
0 01 0
```位移只有一个单位，但x+y从偶数变为奇数。 算法立即拒绝它。 这种情况很有用，因为它可以防止常见错误，即假设足够多的旋转可以模拟任意单位移动。 可用的平移沿着对角线移动，并且奇偶校验不变量不能被破坏。
