 ## 解决方案
 ## 问题理解

 机器人在整数网格上移动。 有两个固定的旋转中心，第一个位于 (0,0)，第二个位于 (1,0)。 每个命令都会将当前位置围绕这两个中心之一顺时针或逆时针旋转 90 ∘。 

这四个命令可以直接写成坐标变换。 以(0,0)为中心，命令1和2分别为顺时针和逆时针旋转。 围绕(1,0)，命令3和4是相应的旋转。 我们从 (x 1 ​ ,y 1 ​ ) 开始，需要到达 (x 2 ​ ,y 2 ​ )，最多生成 10 6 个命令或报告目标无法到达。 

所有坐标的绝对值最多为 100000。输出限制远大于坐标范围，因此使用每单位位移的恒定操作数的构造很容易足够快。 我们无法承受的是搜索指数数量的命令序列，或者探索具有大半径的平面的二次大小区域。 

第一个不明显的问题是可达性。 每个允许的旋转都会保留 x+y 的奇偶校验。 例如，从 (0,0) 开始，绕任一塔旋转总是会产生一个坐标和为偶数的点。 因此 (0,0) 不能到达 (1,0)，因为它们的和具有不同的奇偶性。 仅检查坐标差是否为整数的粗心构造会错误地声称该目标是可到达的。 

第二个问题是两个塔不会直接生成任意单元转换。 有用的翻译有对角线方向。 例如，命令`23`将每个点移动 (1,1)，而命令`14`将每个点移动 (1,−1)。 因此，这两个平移的系数必须是整数。 这与奇偶校验条件完全相同，因为求解

 a(1,1)+b(1,−1)=(dx,dy)

 给出

 a= 2 dx+dy ​ ,b= 2 dx−dy ​ .

 例如，输入```
0 0
1 0
```必须产生`-1`，因为坐标和奇偶性不同。 一种独立尝试通过单位移动来修复 x 和 y 的方法将默默地构造一个不存在的操作序列。 

源和目的地保证不同。 因此我们永远不需要输出零命令。 一个案例如```
5 5
5 -5
```有效且可达，因为两个坐标和都是偶数。 它还捕获假设两个坐标都必须更改的实现。 

## 方法

 直接的暴力方法是枚举命令序列并模拟机器人，直到找到目标。 这是正确的，因为每个可能的序列都被考虑了，但它几乎立即变得无用。 如果我们枚举长度至多为 k 的所有序列，则序列的数量为

 1+4+4 2 +⋯+4 k = 3 4 k+1 −1 ​ 。 

在允许的极限 k=10 6 下，这大约为 4 10 6 /3，远远超出了任何可行的计算。 即使仅检查几十个命令的序列也是不切实际的。 

位置上的 BFS 更好，因为许多不同的命令序列可以到达相同的位置。 它会正确地发现可达组件，但在少数状态后它仍然没有理由停止。 目标坐标可以相距 100000 个单位，因此通用网格搜索可以在找到合适的路径之前访问巨大的区域。 

关键的观察是两个命令可以配对成一个纯翻译。 应用命令 2，绕 (0,0) 逆时针旋转，然后应用命令 3，绕 (1,0) 顺时针旋转。 对于点 (x,y)，命令 2 给出

 (−y,x),

 然后命令 3 给出

 (1+x,1+y)。 

因此`23`将每个点精确平移 (1,1)。 

类似地，命令 1 后跟命令 4 给出

 (x,y)→(y,−x)→(x+1,y−1),

 所以`14`将每个点平移 (1,−1)。 

暴力破解之所以有效，是因为这四个命令描述了完整的转换图。 它失败了，因为该图太大了。 两个命令组合是翻译的观察结果让我们可以用求解二变量线性方程来代替图搜索。 

让

 dx=x 2 ​ −x 1 ​ ,dy=y 2 ​ −y 1 ​ 。 

我们想要

 dx=a+b,dy=a−b,

 其中使用翻译 (1,1) 的 a 副本和翻译 (1,−1) 的 b 副本。 这给出了

 a= 2 dx+dy ​ ,b= 2 dx−dy ​ .

 当 dx 和 dy 具有相同奇偶性时，这些值恰好是整数，相当于 x+y 的起点和终点具有相同奇偶性。 

负系数不会造成任何困难。 的逆`23`是`41`， 所以`41`平移 (−1,−1)。 的逆`14`是`32`， 所以`32`平移 (−1,1)。 

命令数量仅为

 2(∣a∣+∣b∣)。 

使用

 ∣dx+dy∣+∣dx−dy∣=2max(∣dx∣,∣dy∣),

 我们得到

 2(∣a∣+∣b∣)=2max(∣dx∣,∣dy∣)≤400000。 

因此该结构完全低于 10 6 的限制。

 ## 算法演练

 1. 计算位移

 dx=x 2 ​ −x 1 ​ ,dy=y 2 ​ −y 1 ​ 。 

现在可以将整个问题视为使用两个对角线平移构建此位移。 
2. 检查 x 1 ​ +y 1 ​ 和 x 2 ​ +y 2 ​ 奇偶校验是否相同。 同样，检查 dx+dy 和 dx−dy 是否都是偶数。 如果没有，则输出`-1`。 

这不仅仅是我们建筑的财产。 每次允许的旋转都会保留 x+y 的奇偶校验，因此不同的奇偶校验意味着目标确实无法到达。 
3. 计算

 a= 2 dx+dy ​ ,b= 2 dx−dy ​ .

 值 a 告诉我们应用平移 (1,1) 次数，而 b 告诉我们应用平移 (1,−1) 次数。 
4. 如果a>0，则追加`23`正好一次。 如果a<0，则追加`41`正好 -a 次。`23`按 (1,1) 平移，并且`41`是它的倒数，所以它平移 (−1,−1)。 
5. 如果b>0，则追加`14`正好b次。 如果 b<0，则追加`32`正好 -b 次。`14`平移 (1,−1)，而`32`按其逆 (−1,1) 平移。 
6. 输出结果命令字符串。 由于原始位置和目标位置不同，因此至少有一个系数非零，因此命令计数为正。 

### 为什么它有效

 不变量是由生成的命令前缀表示的位移。 每对`23`每对贡献精确 (1,1)`41`每对贡献恰好 (−1,−1)`14`正好贡献 (1,−1)，并且每对`32`正好贡献 (−1,1)。 所选系数满足

 a(1,1)+b(1,−1)=(dx,dy),

 因此，在执行整个序列后，机器人已从 (x 1 ​ ,y 1 ​ ) 精确移动所需的位移并到达 (x 2 ​ ,y 2 ​ )。 

如果奇偶校验测试失败，则任何序列都无法工作，因为每个单独的旋转都会保留 x+y 模 2。因此，该算法会完全拒绝无法到达的情况。 

## Python 解决方案

 编辑```python
import sys
input = sys.stdin.readline

def solve():
    x1, y1 = map(int, input().split())
    x2, y2 = map(int, input().split())

    dx = x2 - x1
    dy = y2 - y1

    # Every operation preserves (x + y) modulo 2.
    if ((x1 + y1) & 1) != ((x2 + y2) & 1):
        print(-1)
        return

    a = (dx + dy) // 2
    b = (dx - dy) // 2

    ans = []

    if a > 0:
        ans.append("23" * a)
    elif a < 0:
        ans.append("41" * (-a))

    if b > 0:
        ans.append("14" * b)
    elif b < 0:
        ans.append("32" * (-b))

    s = "".join(ans)

    print(len(s))
    print(s)

if __name__ == "__main__":
    solve()
```第一部分读取两个位置并将问题转换为位移 (dx,dy)。 使用位移比在每个单独的命令之后尝试操纵当前位置更简单。 

奇偶校验发生在除法之前。 如果奇偶校验不同，则 dx+dy 为奇数，因此所需的系数 a 将不是整数。 更根本的是，目标无法实现，因此不应尝试建设。 

的表达式为`a`和`b`仅在奇偶校验条件确定两个分子均为偶数后才使用整数除法。 Python 整数也具有任意精度，尽管给定的范围足够小，普通的固定宽度整数算术在其他语言中就足够了。 

每个系数都直接转换为重复的两个命令翻译。 两个翻译系列之间的顺序并不重要，因为翻译可以交换，因此实现可以发出一种类型的所有副本，然后发出另一种类型的所有副本。 

输出字符串被显式存储，因为问题需要实际的序列。 它的最大长度为 400000，因此仅使用几百 KB 加上正常的 Python 字符串开销。

## 测试用例

 由于有效输出不是唯一的，因此下面的测试助手通过模拟每个命令来验证返回的命令序列。 这比与一个特定的预期字符串进行比较要强。

def solve():

    x1, y1 = map(int, input().split())
    x2, y2 = map(int, input().split())

    dx = x2 - x1
    dy = y2 - y1

    if ((x1 + y1) & 1) != ((x2 + y2) & 1):
        print(-1)
        return

    a = (dx + dy) // 2
    b = (dx - dy) // 2

    ans = []

    if a > 0:
        ans.append("23" * a)
    elif a < 0:
        ans.append("41" * (-a))

    if b > 0:
        ans.append("14" * b)
    elif b < 0:
        ans.append("32" * (-b))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def validate(inp: str, out: str):
    data = list(map(int, inp.split()))
    x1, y1, x2, y2 = data

    lines = out.strip().splitlines()

    if lines[0] == "-1":
        assert (x1 + y1) % 2 != (x2 + y2) % 2
        return

    k = int(lines[0])
    s = lines[1].strip()

    assert k == len(s)
    assert 0 < k <= 10**6
    assert all(c in "1234" for c in s)

    x, y = x1, y1

    for c in s:
        if c == "1":
            x, y = y, -x
        elif c == "2":
            x, y = -y, x
        elif c == "3":
            x, y = 1 + y, 1 - x
        else:
            x, y = 1 - y, x - 1

    assert (x, y) == (x2, y2)

validate(case2, out)

 ## 边缘情况

 对于不同的奇偶校验，请考虑```
0 0
1 0
```x+y的起始值为0，目标值为1。算法立即拒绝。 这是必要的，因为命令 1 将 (x,y) 更改为 (y,−x)，其总和与 x+y 具有相同的奇偶校验，并且相同的属性也适用于其他三个命令。 

对于负对角线位移，考虑```
0 0
-3 -3
```这里

 a= 2 −3−3 ​ =−3,b=0.

 该算法发出`41`三次。 每个`41`平移 (−1,−1)，因此总位移为 (−3,−3)。 这抓住了仅具有正系数构造的常见错误。 

对于使用另一个对角线方向的位移，请考虑```
0 0
3 -3
```现在a=0且b=3，所以答案是`141414`。 每个`14`贡献 (1,−1)，精确给出 (3,−3)。 

对于最大可达到的位移，```
-100000 -100000
100000 100000
```我们得到 a=200000 和 b=0。 答案包含200000份`23`，发出 400000 个命令。 这低于所需的 10 6 限制，并说明了为什么与坐标距离成比例的构造是安全的。 

对于相同 x 的情况```
5 5
5 -5
```我们得到 dx=0，dy=−10，因此 a=−5 和 b=5。 该建筑结合了五`41`与五个配对`14`对。 他们的总位移是

 5(−1,−1)+5(1,−1)=(0,−10),

 因此，无需特殊情况即可自然处理未更改的 x 坐标。
