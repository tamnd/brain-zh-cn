 ## 解决方案
 ## 问题理解

 机器人在整数平面内运动，有两个固定的旋转中心，即点((0,0))和((1,0))。 每个命令都会围绕这两个中心之一顺时针或逆时针精确旋转当前位置 (90^\circ)。 因此，这四个命令只是当前坐标的四个仿射变换。 

如果当前点是 ((x,y))，则变换为

 [
 1:(x,y)\mapsto(y,-x),
 ]

 [
 2:(x,y)\mapsto(-y,x),
 ]

 [
 3:(x,y)\mapsto(y+1,1-x),
 ]

 [
 4:(x,y)\mapsto(1-y,x-1)。 
]

 我们有一个起点和一个不同的目的地。 任务是输出最多 (10^6) 个命令的任意序列，将第一个点转换为第二个点，或者在不存在此类序列时输出 (-1)。 

坐标的绝对值以 (100000) 为界，因此两个点之间的位移在任一坐标中最多为 (200000)。 显式探索巨大状态图的方法是不必要的，而且有潜在危险，因为所需的答案本身可能包含数十万条命令。 我们想要一个运行时间基本上与输出长度成正比的结构，在这里它很容易足够快。 

粗心的构造可能会错误处理两种边缘情况。 首先，平等是必要的。 例如，```
0 1
1 1
```必须产生`-1`。 每个命令都保留 (x+y) 的奇偶性，因此两个点无法连接。 仅检查坐标是否看起来“接近”的搜索可能会错过这个不变量。 

其次，保证目的地与起点不同，但中间翻译可以具有零系数。 例如，```
0 0
1 1
```只需要 ((1,1)) 方向上的一个单位平移。 当只需要一个方向时，一种构造必须允许一个系数为零，而不是意外地发出空答案。 

所提供语句中的示例在其第二个输入中存在格式损坏，但原始问题给出的第二个示例为```
0 1
1 1
```带输出`-1`。 

## 方法

 直接的暴力方法是将每个整数点视为图顶点，并尝试从每个可达点开始的所有四个命令。 每次移动都是确定性的，因此只要目标可达，广度优先搜索最终都会找到最短的序列。 这是正确的，因为每个合法命令都由一条边表示。 

问题是平面是无界的，即使在与输入相关的坐标范围内，也有大约 (400000^2) 个可能的整数位置。 这大约是 (1.6\cdot10^{11}) 状态，远远超出了两秒实现所能探索的范围。 即使搜索半径小得多也是不可接受的。 

有用的观察结果是，结合围绕两个不同中心的旋转会产生平移。 执行命令 (1)，然后执行命令 (4)。 命令(1)绕原点顺时针旋转，命令(4)绕((1,0))逆时针旋转。 从代数上来说，

 [
 (x,y)\x右箭头{1}(y,-x)
 \xrightarrow{4}(x+1,y-1)。 
]

 因此两个命令序列`14`将每个点精确移动 ((1,-1))，无论其当前坐标如何。 

它的倒数是`32`，将每个点移动 ((-1,1))。 

现在将这个平移旋转 (90^\circ)。 顺序`1142`是一个共轭`14`并将每个点移动 ((1,1))。 它的倒数是`1322`，将每个点移动 ((-1,-1))。 

这将几何问题简化为普通的整数算术。 如果需要的位移是

 [
 (dx,dy)=(x_2-x_1,y_2-y_1),
 ]

 我们可以把它写成

 a(1,1)+b(1,-1),
 ]

 哪里

 [
 a=\frac{dx+dy}{2},
 \qquad
 b=\frac{dx-dy}{2}。 
]

 当 (dx) 和 (dy) 具有相同奇偶校验时，即当 (x_1+y_1) 和 (x_2+y_2) 具有相同奇偶校验时，这些系数恰好是整数。 

这个奇偶条件也是必要的。 在命令（1）下，

 [
 x+y\映射到 y-x,
 ]

 与 (x+y) 具有相同的奇偶性。 相同的计算适用于所有四个命令。 因此 (x+y) 的奇偶校验是整个过程的不变量。 

所以这个条件既是必要的，又是充分的。 当它成立时，我们只需将两个可用翻译重复所需的次数即可。 

(a) 或 (b) 的最大可能绝对值为 (200000)。 对角线平移每个单元使用四个命令，((1,-1)) 平移每个单元使用两个命令。 最坏的情况是最多 (800000) 个命令，因此可以轻松满足所需的 (10^6) 限制。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | (O(V+E))，可能为 (10^{11}) 状态 | (O(V)) | 太慢了|
 | 翻译建设| (O( | a | + | b | )) | (O( | a | + | b | )) 得到答案 | 已接受 |

 ## 算法演练

 1.读取起点((x_1,y_1))和终点((x_2,y_2))，然后计算

 [
 dx=x_2-x_1,\qquad dy=y_2-y_1。 
]

 整个构造仅取决于这种位移，因为生成的平移在任何地方都表现相同。 

1. 检查(dx)和(dy)的奇偶校验是否相同。 同样，检查是否

 [
 (dx+dy)\bmod 2=0。 
]

 如果这是假的，则打印`-1`。 每个合法命令都会保留 (x+y) 的奇偶校验，因此任何序列都无法到达目的地。 

1. 计算

 [
 a=\frac{dx+dy}{2},\qquad b=\frac{dx-dy}{2}.
 ]

 然后

 # (a+b,a-b)

 (dx,dy)。 
]

 位移现在已分解为我们知道如何生成的两个平移。 

1. 如果 (a>0)，则追加`1142`正好 (a) 次。 该序列将当前点平移 ((1,1))。 如果 (a<0)，则追加`1322`正好 (-a) 次，平移 ((-1,-1))。 

中的四个命令`1142`不是任意的伎俩。 它们是基本翻译的共轭`14`旋转了(90^\circ)，所以它的位移就是旋转后的向量((1,-1))，即((1,1))。 

1. 如果 (b>0)，则追加`14`正好 (b) 次。 如果 (b<0)，则追加`32`正好 (-b) 次。 这些翻译贡献了(b(1,-1))。 
2. 生成的命令字符串具有精确的位移

 [
 a(1,1)+b(1,-1)=(dx,dy),
 ]

 所以机器人在 ((x_2,y_2)) 处完成。 打印它的长度和字符串。 

### 为什么它有效

 中心不变量是 (x+y) 的奇偶性。 每个单独的命令都会保留它，证明不同的奇偶校验类别永远无法通信。 当奇偶校验匹配时，(dx)和(dy)具有相同的奇偶校验，因此(a)和(b)是整数。 命令序列`14`,`32`,`1142`， 和`1322`分别通过 ((1,-1))、((-1,1))、((1,1)) 和 ((-1,-1)) 实现翻译。 它们的组合产生两个坐标具有相同奇偶性的每个位移。 因此，该算法对于可到达的点对完全成功。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    x1, y1 = map(int, input().split())
    x2, y2 = map(int, input().split())

    dx = x2 - x1
    dy = y2 - y1

    # Every operation preserves the parity of x + y.
    if (dx + dy) & 1:
        print(-1)
        return

    a = (dx + dy) // 2
    b = (dx - dy) // 2

    ans = []

    if a > 0:
        ans.append("1142" * a)
    elif a < 0:
        ans.append("1322" * (-a))

    if b > 0:
        ans.append("14" * b)
    elif b < 0:
        ans.append("32" * (-b))

    s = "".join(ans)

    print(len(s))
    print(s)

if __name__ == "__main__":
    solve()
```第一个奇偶校验直接对应于可达性不变量。 使用`(dx + dy) & 1`对于负 Python 整数也是安全的，因为它检查整数的奇偶校验而不依赖于浮点运算。 

仅在奇偶校验测试确定两个分子均为偶数后，才使用整数除法计算系数。 不涉及舍入。 

对于正数 (a)，`1142`重复是因为它通过 ((1,1)) 进行平移。 对于负数 (a)，`1322`是它的倒数。 同样地，`14`和`32`是沿 ((1,-1)) 方向的逆平移。 

答案被组装为字符串，而不是在嵌套的 Python 操作中附加单个字符。 最大的答案低于 (10^6) 个字符，因此这完全在正常的内存限制范围内。 

两个翻译组的顺序并不重要，因为翻译是可交换的。 首先应用所有对角线平移，然后应用所有反对角线平移，给出与任何其他顺序完全相同的最终位移。 

## 工作示例

 ### 示例 1

 第一个样本从 ((0,1)) 开始，想要到达 ((1,-2))。 

位移及其分解为：

 | 变量| 价值|
 | --- | --- |
 | (dx) | (1) |
 | (dy)| (-3) |
 | (dx+dy) | (-2) |
 | (a=(dx+dy)/2) | (-1) |
 | (b=(dx-dy)/2) | (2) |

 由于 (a=-1)，该算法发出`1322`，移动 ((-1,-1))。 由于 (b=2)，它发出`1414`，移动 ((2,-2))。 

总位移为

 [
 (-1,-1)+(2,-2)=(1,-3),
 ]

 所以

 [
 (0,1)+(1,-3)=(1,-2)。 
]

 因此，该算法输出八个命令的有效序列。 官方示例恰好使用了更短的序列`24`，但不需要最小化长度。 该问题接受最多 (10^6) 个命令的任何有效序列。 

### 示例 2

 原来的第二个样本是```
0 1
1 1
```位移为((1,0))。 

| 变量| 价值|
 | --- | --- |
 | (dx) | (1) |
 | (dy)| (0) |
 | (dx+dy) | (1) |
 | 奇偶校验| 失败|
 | 结果 |`-1`|

 两个位移坐标具有不同的奇偶性，因此不存在满足的整数对(a,b)

 [
 (dx,dy)=a(1,1)+b(1,-1)。 
]

 更根本的是，起点为 (x+y=1)，而目的地为 (x+y=2)。 由于每个命令都保留该奇偶校验，因此目标无法访问。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | (O( | a | + | b | )) | 每个生成的命令都会附加一次，因此工作量与输出长度呈线性关系。 |
 | 空间| (O( | a | + | b | )) | 命令字符串本身需要线性空间。 |

 由于每个坐标最多相差 (200000)，因此两个系数的绝对值最多为 (200000)。 该结构对 (a) 的每个单元使用 4 个命令，对 (b) 的每个单元使用 2 个命令，最多给出 (800000) 个命令。 这低于所需的 (10^6) 界限，并且运行时间和内存使用量都很容易管理。 

## 测试用例

 由于有效答案不是唯一的，因此测试应该验证生成的命令序列，而不是比较确切的命令字符串。 下面的助手独立模拟所有四种转换并检查最终位置是否正确。 它还检查 (10^6) 命令限制。```python
import sys
import io

def solve_data(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        x1, y1 = map(int, input().split())
        x2, y2 = map(int, input().split())

        dx = x2 - x1
        dy = y2 - y1

        if (dx + dy) & 1:
            return "-1\n"

        a = (dx + dy) // 2
        b = (dx - dy) // 2

        ans = []

        if a > 0:
            ans.append("1142" * a)
        elif a < 0:
            ans.append("1322" * (-a))

        if b > 0:
            ans.append("14" * b)
        elif b < 0:
            ans.append("32" * (-b))

        s = "".join(ans)
        return f"{len(s)}\n{s}\n"
    finally:
        sys.stdin = old_stdin

def run(inp: str) -> str:
    return solve_data(inp)

def verify(inp: str):
    x1, y1 = map(int, inp.splitlines()[0].split())
    x2, y2 = map(int, inp.splitlines()[1].split())

    out = run(inp).strip().splitlines()

    if out[0] == "-1":
        return False, "reported impossible"

    k = int(out[0])
    s = out[1]

    assert k == len(s)
    assert 0 < k <= 10**6
    assert all(c in "1234" for c in s)

    x, y = x1, y1

    for c in s:
        if c == "1":
            x, y = y, -x
        elif c == "2":
            x, y = -y, x
        elif c == "3":
            x, y = y + 1, 1 - x
        else:
            x, y = 1 - y, x - 1

    return (x, y) == (x2, y2), (x, y)

# Provided sample 1. Any valid sequence is accepted.
ok, _ = verify("0 1\n1 -2\n")
assert ok, "sample 1"

# Provided sample 2 from the original statement.
assert run("0 1\n1 1\n").strip() == "-1", "sample 2"

# Minimum-size displacement that is reachable.
ok, _ = verify("0 0\n1 1\n")
assert ok, "unit diagonal translation"

# Negative diagonal displacement.
ok, _ = verify("0 0\n-1 -1\n")
assert ok, "negative diagonal translation"

# Boundary-sized reachable displacement.
ok, _ = verify("-100000 -100000\n100000 100000\n")
assert ok, "maximum diagonal displacement"

# Boundary-sized unreachable displacement.
assert run("-100000 -100000\n100000 99999\n").strip() == "-1", \
    "boundary parity case"
```| 测试输入| 预期产出 | 它验证了什么 |
 | --- | --- | --- |

 ## 边缘情况

 第一个不明显的情况是奇偶校验导致的不可达点。 为了```
0 1
1 1
```我们有 (dx=1) 和 (dy=0)，所以 (dx+dy=1) 是奇数。 算法立即停止并打印`-1`。 这比尝试构建序列并在长时间搜索后才发现失败更好。 

第二种情况是完全沿着一个生成方向的位移。 为了```
0 0
1 1
```我们得到 (a=1) 和 (b=0)。 该算法准确地发出`1142`。 应用这四个命令给出

 [
 (0,0)\x右箭头{1}(0,0)
 \xrightarrow{1}(0,0)
 \xrightarrow{4}(1,-1)
 \xrightarrow{2}(1,1)。 
]

 前两次旋转取消，因为机器人从第一个塔开始，并且完整的序列仍然实现所需的平移。 

负系数通过使用逆序列来处理。 为了```
0 0
-1 -1
```我们得到 (a=-1)，所以算法发出`1322`。 其净位移为((-1,-1))，从起点直接到达终点。 

可达到的最大位移也是安全的。 为了```
-100000 -100000
100000 100000
```我们有 (dx=dy=200000)，因此 (a=200000) 和 (b=0)。 输出包含 (4\cdot200000=800000) 个命令，低于 (10^6) 限制。 这是建筑输出尺寸的最坏情况。 

最后，零系数不得导致算法打印空命令字符串。 例如，如果只有 (b) 不为零，则简单地跳过对角线平移块，并且`14`或者`32`块提供整个位移。 由于保证原始点不同，因此 (a) 和 (b) 至少其中之一不为零，因此只要目标可达，最终答案始终是正长度命令字符串。
