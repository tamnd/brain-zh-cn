 ## 解决方案
 ## 问题理解

 我们需要计算类斐波那契数列的前 (n+1) 个元素的平方和。 该序列以两个 1 开头，因此它的第一个值是

 [
 1,1,2,3,5,8,\l点
 ]

 后面的每个值都是前两个值的总和。 所需答案是

 [
 f_0^2+f_1^2+\cdots+f_n^2
 ]

 取模 (998,244,353)。 

难度是界限（n\le 10^{18}）。 即使 (O(n)) 算法也需要最多 (10^{18}) 次迭代，远远超出任何实际时间限制。 我们需要一个方法，其运行时间取决于 (n) 的位数，对于 (10^{18}) 来说只有 60 左右。 这使得 (O(\log n)) 算法自然成为目标。 

在一些小情况下，索引错误很容易隐藏。 对于 (n=0)，总和仅包含 (f_0^2=1)，因此答案为 (1)。 使用通常的斐波那契索引而不调整移位的公式可能会错误地返回 (0)。 对于 (n=1)，答案是 (1^2+1^2=2)，它检查是否包含两个初始值。 对于 (n=2)，总和为 (1+1+4=6)，因此仅在生成新的斐波那契值后才开始累加的递归实现将减少 1。 

基于比奈表达式的公式还存在另一个问题。 尽管 Binet 的公式在数学上是正确的，但如果直接实现，它会使用浮点数，并且 (10^{18}) 左右的值需要比标准浮点类型所能提供的精度高得多的精度。 具有整数快速加倍的模运算完全避免了这个问题。 

## 方法

 直接解决方案很简单。 从 (f_0=f_1=1) 开始，重复生成下一个斐波那契值，对其进行平方，然后将平方与答案模 (998,244,353) 相加。 这是正确的，因为每个项都只生成一次，并且每个生成的平方对所需总和只贡献一次。 

问题是（n）的大小。 对于 (n=10^{18})，此方法生成 (10^{18}+1) 个序列项。 如果我们计算每个递归步骤一次加法，每个平方一次乘法，每次累加一次加法，则工作量约为 (3n)，大致为 (3\cdot10^{18}) 个基本算术运算。 确切的计数取决于初始值和累加器的处理方式，但渐近问题是决定性的：线性时间是不可能的。 

有用的观察结果是，问题中的序列只是标准斐波那契序列移动了一个位置。 令(F_0=0,F_1=1)。 然后

 [
 f_i=F_{i+1}。 
]

 还有一个经典的身份

 [
 \sum_{k=1}^{m}F_k^2=F_mF_{m+1}。 
]

 设置 (m=n+1) 给出

 # \sum_{i=0}^{n}F_{i+1}^2

 F_{n+1}F_{n+2}。 
]

 因此，整个求和已分解为两个斐波那契数的乘积。 

我们仍然需要计算索引可以大到 (10^{18}+2) 的斐波那契数。 快速倍增正是在 (O(\log n)) 时间内完成的。 该技术使用直接从 (F_k) 和 (F_{k+1}) 导出 (F_{2k}) 和 (F_{2k+1}) 的恒等式：

 [
 F_{2k}=F_k(2F_{k+1}-F_k)
 ]

 和

 [
 F_{2k+1}=F_k^2+F_{k+1}^2。 
]

 因此，在递归解决 (k=\lfloor n/2\rfloor) 的问题后，我们可以仅使用恒定数量的模乘法和加法来构造 (n) 的答案。 

蛮力方法之所以有效，是因为递归可以让我们枚举每个所需的术语。 它会失败，因为可能有 (10^{18}+1) 个。 斐波那契平方和具有闭合形式的观察结果将问题简化为计算一对斐波那契对，而快速加倍则将该计算从线性时间缩短为对数时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | (O(n)) | (O(n)) | (O(1)) | (O(1)) | 太慢了 |
 | 最佳 | (O(\log n)) | (O(\log n)) | 已接受 |

 ## 算法演练

1. 介绍标准斐波那契数列（F_0=0,F_1=1）。 问题的序列满足 (f_i=F_{i+1})，因此所需的总和变为

 [
 \sum_{i=0}^{n}F_{i+1}^2。 
]

 索引的这种变化是可能发生相差一错误的主要地方。 

1.申请身份

 [
 \sum_{k=1}^{m}F_k^2=F_mF_{m+1}。 
]

 对于 (m=n+1)，所需答案为

 [
 F_{n+1}F_{n+2}。 
]

 因此，我们只需要连续的对 ((F_{n+1},F_{n+2}))。 

1. 定义一个返回对 ((F_k,F_{k+1})) 的函数。 对于 (k=0)，该对是 ((0,1))。 
2. 递归计算 (k=\lfloor n/2\rfloor) 对。 假设它返回 ((a,b)=(F_k,F_{k+1}))。 
3. 利用快速倍增恒等式获得

 [
 c=F_{2k}=a(2b-a)
 ]

 和

 [
 d=F_{2k+1}=a^2+b^2。 
]

 所有运算均以模 (998,244,353) 执行。 

1. 如果 (n) 是偶数，则返回 ((c,d))，因为 (n=2k)。 

如果 (n) 为奇数，则返回 ((d,c+d))，因为 (n=2k+1) 且 (F_{2k+2}=F_{2k}+F_{2k+1})。 

1. 使用 (n+1) 调用该函数。 如果它返回 ((x,y))，则 (x=F_{n+1}) 和 (y=F_{n+2})。 输出（xy\bmod 998,244,353）。 

### 为什么它有效

 递归函数的不变量是`fib_pair(k)`始终准确返回 ((F_k,F_{k+1}))。 基本情况直接返回((F_0,F_1)=(0,1))。 对于较大的 (k)，递归调用给出 (\lfloor k/2\rfloor) 的正确对，并且加倍恒等式生成索引 (2\lfloor k/2\rfloor) 和 (2\lfloor k/2\rfloor+1) 的精确值。 然后奇偶校验为 (k) 选择适当的对。 因此，最终调用返回 ((F_{n+1},F_{n+2}))，其乘积等于斐波那契平方和恒等式的原始总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def fib_pair(n):
    if n == 0:
        return 0, 1

    a, b = fib_pair(n // 2)

    c = a * ((2 * b - a) % MOD) % MOD
    d = (a * a + b * b) % MOD

    if n % 2 == 0:
        return c, d

    return d, (c + d) % MOD

def solve():
    n = int(input())

    fn1, fn2 = fib_pair(n + 1)
    answer = fn1 * fn2 % MOD

    print(answer)

if __name__ == "__main__":
    solve()
```常数`MOD`存储所需的模数。 保持每个斐波那契中间值的模数减少`MOD`就足够了，因为后面的所有运算都是加法和乘法，两者都遵循模等价。 

递归函数返回两个连续的斐波那契数，而不是仅一个。 这是必要的，因为 (F_{2k}) 的倍增公式同时使用 (F_k) 和 (F_{k+1})。 返回该对还意味着奇数情况可以通过最后一次加法获得 (F_{2k+2})。 

表达式`2 * b - a`在模运算之前可以为负数，因此代码显式计算`(2 * b - a) % MOD`。 Python 的模运算正确处理负中间值，产生所需范围内的值。 

调用使用`n + 1`， 不是`n`。 原始序列相对于标准斐波那契序列进行了平移，平方和恒等式需要 (F_{n+1}F_{n+2})。 自从`fib_pair(n + 1)`返回从 (F_{n+1}) 开始的连续值，乘法正是所需的答案。 

Python 整数具有任意精度，因此不存在整数溢出。 更重要的是，该算法从未构造出巨大的实际斐波那契数。 每个值立即按模 (998,244,353) 减少。 

## 工作示例

 对于样品 1，(n=0)。 该算法要求索引 (n+1=1) 处的对。 

| 步骤| (n) | 已退回一双 | 意义|
 | ---| ---| ---| ---|
 | 基地| 0 | ((0,1)) | ((0,1)) | (F_0,F_1) | (F_0,F_1) |
 | 奇案| 1 | ((1,1)) | ((1,1)) | (F_1,F_2) | (F_1,F_2) |
 | 决赛| 0 | (1\cdot1) | (1) |

 返回的对是((F_1,F_2)=(1,1))，所以答案是(1)。 这确认了可能的最小输入并验证是否包含 (f_0)。 

对于样品 2，(n=2)。 我们需要索引 (3) 处的对。 

| 步骤| 当前指数| 半指数| 配对半 | 配对当前 |
 | ---| ---| ---| ---| ---|
 | 基地| 0 | 0 | ((0,1)) | ((0,1)) | ((0,1)) | ((0,1)) |
 | 加倍| 1 | 0 | ((0,1)) | ((0,1)) | ((1,1)) | ((1,1)) |
 | 加倍| 3 | 1 | ((1,1)) | ((1,1)) | ((2,3)) | ((2,3)) |
 | 最终产品| 2 | 3 | ((2,3)) | ((2,3)) | (2\cdot3=6) |

 这里返回的对是 ((F_3,F_4)=(2,3))。 他们的乘积是 (6)，匹配

 [
 1^2+1^2+2^2=6。 
]

 该跟踪还说明了该函数返回两个连续值的原因。 ((2,3)) 对给出了最终封闭形式所需的两个斐波那契数。

## 边缘情况

 对于 (n=0)，输入为`0`。 该算法调用`fib_pair(1)`，返回 ((1,1))。 最终的乘法是 (1\cdot1=1)，匹配唯一项 (f_0^2=1)。 忘记从 (f_i) 到 (F_{i+1}) 的转变的公式可能会立即失败。 

对于 (n=1)，输入为`1`。 所需的总和为 (1^2+1^2=2)。 该算法计算`fib_pair(2)`，得到((F_2,F_3)=(1,2))，并将它们相乘得到(2)。 这捕获了一个意外地仅使用两个初始值之一开始求和的实现。 

对于 (n=2)，输入为`2`。 涉及的标准斐波那契值为(F_1,F_2,F_3=1,1,2)，所以答案为(1+1+4=6)。 算法得到`fib_pair(3)=(2,3)`并计算 (2\cdot3=6)。 这是检查超出初始条件的平方和恒等式的最简单情况。 

对于 (n=10^{18})，输入位于允许的最大索引处。 该算法从不迭代该序列。 每次递归调用都会用其整数一半替换当前索引，因此该链仅包含大约 60 个级别。 每个斐波那契值都会按模 (998,244,353) 减少，因此即使实际的斐波那契数有大量位数，计算量仍然很小。 所得乘积再次以所需模数为模进行减少，从而准确给出所需的答案。
