 ## 解决方案
 ## 问题理解

 我们有一系列正值`a[1..n]`。 两名玩家从左到右处理它。 在每一回合中，当前玩家可以从前面丢弃任意数量的仍未使用的元素，然后获取下一个元素。 因此，当一名球员就位后`j`，每个位置直到`j`消失了，下一个玩家从`j + 1`。 

玩家可以跳过元素，因为他们可以在获取元素之前销毁某些前缀。 目标不是最大化各个元素的总和，而是最大化玩家自己的总和与对手的总和之间的差异。 山姆先移动，所以我们需要最优值`Sam's sum - Catcher's sum`。 

该数组最多可以包含`200000`元素，而每个值都可以大到`10^9`。 官方声明给出了2秒的时间限制和512MB的内存限制。 一个`O(n^2)`算法将执行大约`n(n+1)/2`，或者粗略地`20,000,100,000`，候选者以最大尺寸进行转换，这远远超出了时间限制。 我们需要一个`O(n)`或接近`O(n log n)`解决方案。 答案本身可以大到`10^9`，Python 整数可以安全地处理它，无需任何特殊的溢出处理。 

有几个小案例暴露了常见的错误。 为了`n = 1`和`a = [7]`，答案是`7`，因为 Sam 只是采用唯一的元素。 为了`n = 2`和`a = [1, 100]`，答案是`100`：山姆可以丢弃`1`并立即采取`100`，没有给第二个玩家留下任何东西。 假设必须采用每个元素的解决方案将错误地得到`-99`。 反之，对于`n = 2`和`a = [5, 1]`, 萨姆应该采取`5`，之后对手得到`1`, 给予`4`。 总是跳转到最大剩余值的贪心规则在这里恰好起作用，但这并不是解决方案正确的原因。 

平等的价值观也值得关注。 为了`[1, 1, 1, 1]`，答案是`1`， 不是`0`或者`2`。 山姆可以拿一个`1`，对手可以再拿一个，但玩家也可以跳过元素。 正确的循环必须考虑到每个可能的下一个位置，而不是假设玩家只是简单地交替相邻元素。 

## 方法

 直接动态规划公式已经足以准确描述游戏。 让`dp[i]`是剩余数组从位置开始时轮到玩家的最佳得分差`i`。 假设玩家选择位置`j`， 在哪里`j >= i`。 他们收到`a[j]`，剩下的整个游戏开始于`j + 1`随对手移动。 从当前玩家的角度来看，未来的游戏是值得的`dp[j + 1]`对对手来说，所以有贡献`-dp[j + 1]`到当前玩家的分数。 选择`j`因此给出`a[j] - dp[j + 1]`。 

采取最佳可能的选择给出`dp[i] = max(a[j] - dp[j + 1])`为所有人`j >= i`，

和`dp[n + 1] = 0`。 

这种重复是正确的，因为每个合法的移动都完全由当前玩家选择的位置来表征。 一旦确定了该位置，就只剩下一场比赛，即该位置之后的后缀。 

蛮力实现独立评估每个的最大值`i`。 为了`i = 1`它检查`n`选择，对于`i = 2`它检查`n - 1`， 等等。 检查总数为`n + (n - 1) + ... + 1 = n(n+1)/2`。 在`n = 200000`， 那是`20,000,100,000`检查，所以二次版本无法通过。 

关键的观察是最大化的表达式具有特殊的形式。 当我们计算时`dp[i]`, 每个候选人都是`a[j] - dp[j + 1]`。 属于位置的值`j`不依赖于`i`。 当我们从右向左移动时，我们只添加一个新的候选者，即与当前位置相对应的候选者。 我们可以维持到目前为止看到的最大候选，而不是再次扫描整个后缀。 这将二次递归变成了单个向后传递。 官方社论中描述了相同的优化：候选值保持固定为`i`减少，因此运行最大值就足够了。 

不需要线段树或其他复杂的数据结构。 查询的范围始终是后缀，并且这些后缀在向后遍历期间恰好增长一个元素。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 将空后缀的值设置为`dp[n + 1] = 0`。 如果没有剩余的构造函数，则不会获得分数差异。 
2. 处理位置`n`下降到`1`。 在位置`i`，担任该职位的候选人是`a[i] - dp[i + 1]`。 出现减法是因为取后`a[i]`，对手成为最优分差为的玩家`dp[i + 1]`。 
3. 维护一个变量`best`包含最大值`a[j] - dp[j + 1]`所有职位中`j`已经处理了。 加工时`i`, 计算`a[i] - dp[i + 1]`并更新`best`与这位候选人。 
4. 设置`dp[i] = best`。 这是有效的，因为国家的法律选择`i`正是位置`i, i + 1, ..., n`， 和`best`正是该后缀的最大候选者。 
5、后加工位置`1`， 输出`dp[1]`，因为该状态是原始游戏，而 Sam 是采取第一步行动的玩家。 

不变的是处理后的位置`i`,`best`等于最大值`a[j] - dp[j + 1]`超过每一个`j >= i`。 最后`dp[i]`正是从 开始的游戏的最优结果`i`。 每个合法的第一步都由一个候选者代表，并且循环说明了该移动之后的最佳延续。 由于递归是从右到左评估的，因此每个所需的`dp[j + 1]`当考虑其候选人时就已经知道了。 因此，运行最大值不能忽略合法的移动或引入非法的移动。 

实现上还有进一步的简化。 我们实际上并不需要存储整个`dp`大批。 加工时`i`， 仅有的`dp[i + 1]`是需要的，并且运行最大值已经代表`dp[i]`。 我们可以为前一个 DP 值保留一个变量，并为当前的最大值保留一个变量。 这将辅助内存减少到`O(1)`超出输入数组。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve(n, a):
    dp_next = 0
    best = -10**30

    for i in range(n - 1, -1, -1):
        candidate = a[i] - dp_next
        if candidate > best:
            best = candidate
        dp_next = best

    return dp_next

def main():
    n = int(input())
    a = list(map(int, input().split()))
    print(solve(n, a))

if __name__ == "__main__":
    main()
```该数组被读取一次，然后循环从其最后一个元素开始。`dp_next`代表`dp[i + 1]`，因此在处理最终位置之前将其初始化为零。 候选人`a[i] - dp_next`正是选择位置得到的值`i`。 

计算出候选人后，`best`在将其分配给之前更新`dp_next`。 这个顺序很重要。 新的`dp[i]`包括采用当前元素的可能性，因此当前候选者必须是`best`前`dp_next`成为下一次迭代的值。 

初始化`-10**30`安全地低于所有可能的候选人。 事实上，因为所有`a[i]`是正数并且分数差受数组总和的限制，普通的 Python 整数已经足够了。 循环完全执行`n`迭代，每次迭代都使用常数时间算术和比较。 

该解决方案使用`O(n)`仅用于输入数组的内存`O(1)`用于动态编程状态的附加内存。 

## 工作示例

 ### 示例 1

 对于`a = [1, 2, 3]`，我们从右到左处理数组。 

| 位置`i`|`a[i]`|`dp_next`| 候选人`a[i] - dp_next`|`best`|`dp[i]`|
 | --- | --- | --- | --- | --- | --- |
 | 3 | 3 | 0 | 3 | 3 | 3 |
 | 2 | 2 | 3 | -1 | 3 | 3 |
 | 1 | 1 | 3 | -2 | 3 | 3 |

 第一个玩家最终可以获得的差异为`3`。 最佳的第一步是放弃`1`和`2`并采取`3`，立即结束游戏。 当处理较早的位置时，运行最大值会正确保留此选项。 

### 示例 2

 对于`a = [3, 2, 1]`，相同的向后计算给出：

 | 位置`i`|`a[i]`|`dp_next`| 候选人`a[i] - dp_next`|`best`|`dp[i]`|
 | --- | --- | --- | --- | --- | --- |
 | 3 | 1 | 0 | 1 | 1 | 1 |
 | 2 | 2 | 1 | 1 | 1 | 1 |
 | 1 | 3 | 1 | 2 | 2 | 2 |

 在第一个位置，采取`3`树叶`[2, 1]`，其对手的最优值为`1`，所以山姆得到`3 - 1 = 2`。 跳到的替代方案`2`或者`1`也好不到哪儿去。 结果是`2`，匹配样本。

 ## 边缘情况

 对于单个构造函数，输入```
1
7
```开始于`dp[2] = 0`。 唯一的候选人是`7 - 0 = 7`， 所以`best`和`dp[1]`两者都成为`7`。 算法输出`7`，正确处理后缀边界，无需特殊情况。 

对于输入```
2
1 100
```最终位置给出`dp[2] = 100`。 在位置`1`，取`1`会产生`1 - 100 = -99`，但职位候选人`2`已经存储在`best`作为`100`。 因此`dp[1] = 100`。 这抓住了关键的规则，即 Sam 可以销毁第一个构造函数并获取第二个构造函数，之后数组为空并且对手无法移动。 

对于输入```
2
5 1
```最终位置给出`dp[2] = 1`。 在位置`1`, 采取`5`给候选人`5 - 1 = 4`，同时取第二个元素给出`1`。 最大值为`4`，所以 Sam 取`5`对手拿走`1`。 这说明了为什么简单地取迄今为止所见的最大值并不是实际的 DP 参数。 一个元素的价值取决于它之后剩下的最佳游戏。 

对于全等输入```
4
1 1 1 1
```落后国家是`dp[4] = 1`,`dp[3] = 1`,`dp[2] = 1`， 和`dp[1] = 1`。 在每个职位上，新候选人都是`1 - 1 = 0`，除了最后一个位置`1`。 因此，运行最大值仍然是`1`。 这证实了该算法可以处理重复的相等候选者，而不依赖于严格的不平等或不同的值。 

最大尺寸的情况包括`200000`元素，全部等于`1`。 每个候选者都会计算一次，因此循环仍然只执行`200000`迭代。 答案依然存在`1`，而二次公式会尝试约`20`十亿候选人支票。 这种情况最清楚地将可接受的解决方案与简单的动态编程实现区分开来。
