 ## 解决方案
 ## 问题理解

 我们有一个城市和道路的无向图。 山姆开始在城市`s`在某个时间`0`并希望尽早抵达城市`t`。 

每条道路都有三个参数。 其遍历时间为`d`。 那条路上的天气是周期性的，有周期

 [
 P=a+b。 
]

 每个时期，道路不时干燥`kP`通过`kP+a`，并且下雨了`kP+a`通过`(k+1)P`。 Sam可以在城市中自由等待，所以当他到达道路的终点时，他只需要选择一个合适的未来干燥间隔。 

时长的穿越`d`只有在道路上度过的整个时间段都是干燥的情况下才可能实现。 如果山姆及时进入道路`x`，他需要

 [
 x+d\le kP+a
 ]

 在适当的时期内。 雨停时准入是允许的，下雨时准时到达也是允许的。 

任务是找到最短可能到达时间`t`， 或者`-1`如果不存在可用的道路序列。 

该图可以包含`100000`顶点和`200000`边缘。 有了这个大小，诸如枚举路径或执行之类的算法`O(nm)`图松弛远远超出了实际的时间限制。 在最坏的情况下，`nm`是关于`2\cdot10^{10}`边缘检查。 我们需要一种近线性图算法，通常约为`O((n+m)\log n)`。 

有几种边界情况可能会导致看似合理的实现出现错误。 首先，道路的行驶时间可能比其整个干燥间隔更长。 例如，```
2 1 1 2
1 2 3 5 4
```这里干燥间隔仅持续`a=3`，而交叉需要`d=4`。 该路永远无法使用，所以正确的输出是`-1`。 粗心的实施，只是等待下一个干旱期并添加`d`会错误地声称该道路是可通行的。 

当遍历恰好在下雨开始时结束时，会出现第二种边界情况。 例如，```
2 1 1 2
1 2 3 5 3
```道路不时干燥`0`通过时间`3`。 山姆可以进入`0`， 花费`3`单位正在路上，并准时到达`3`，正是雨开始的时候。 正确的输出是`3`。 因此，条件必须是`remaining_dry >= d`， 不是`remaining_dry > d`。 

第三个病例是在雨中抵达的。 考虑```
2 1 1 2
1 2 3 5 2
```第一个干燥间隔是`[0,3]`，这样 Sam 就可以立即穿过并到达`2`。 但如果以前的某条路当时把他带到了这条路`4`，他不能立即进入，因为时间`4`处于降雨区间内`[3,8]`。 他必须等到时间`8`，然后穿过并到达`10`。 仅使用`time % period`不区分旱雨部分将导致出发无效。 

最后，当当前到达时间恰好在新的无水间隔开始时，道路可以完全可用。 和`a=3`,`b=5`, 到达时间`8`给出余数`0`，因此可以立即出发。 公式必须处理余数`0`不如等干了再等一段时间。 

## 方法

 直接的强力解决方案可以使用重复的图松弛。 认为`dist[v]`是 Sam 到达城市的已知最早时间`v`。 对于每条边，我们可以计算通过该边的最早到达时间，并重复放松所有边，直到值没有变化。 这本质上是贝尔曼-福特适应时间相关的边缘成本。 

松弛本身是正确的，因为一旦知道端点的到达时间，边缘就有明确定义的最早可能到达时间。 重复松弛最终会沿着包含许多边的路径传播信息。 

问题在于重复次数。 在最坏的情况下，贝尔曼-福特需要`n-1`全部通过，并且每一次通过都检查所有`m`道路。 和`n=100000`和`m=200000`，这取决于

 [
 (n-1)m\约2\cdot10^{10}
 ]

 边缘检查。 这太大了。 

关键的观察结果是，每条道路的行为都类似于具有 FIFO 属性的时间相关边缘。 如果 Sam 较晚到达某个道路端点，则最早到达另一个端点的时间永远不会变早。 等待总是被允许的，最早的可行出发只是可以包含整个遍历的第一个干区间。 

这个属性让我们可以使用 Dijkstra 算法。 通常的 Dijkstra 论点仍然适用：当提取当前最小的暂定到达时间时，没有更晚的路线可以更早到达该城市。 唯一的额外工作是用计算当前时间的最早合法到达时间的函数替换固定边权重。 

假设当前时间是`x`道路有周期`P=a+b`。 让

 [
 r=x\bmod P。 
]

 如果`r <= a-d`，道路在当前干燥间隔内剩余足够的干燥时间，因此 Sam 可以立即出发并到达`x+d`。 

如果`r > a-d`，目前的干燥间隔已经太短了。 山姆必须等到下一个周期开始时`x-r+P`，然后花费`d`时间穿越。 这给出了候选人到达的时间

 [
 x-r+P+d。 
]

什么时候`d>a`，没有一个周期包含足够的干燥时间来进行遍历，因此边缘在两个方向上都无法使用。 

比较是：

 | 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(nm)`|`O(n+m)`| 太慢了 |
 | 最佳 |`O((n+m) log n)`|`O(n+m)`| 已接受 |

 ## 算法演练

 1. 将每条道路存储在两个端点的邻接表中。 每个存储的边都包含另一个端点及其值`a`,`b`， 和`d`，因为道路是双向的，并且每个方向都有相同的天气时间表。 
2.如果`d > a`，放松时忽略道路。 其干燥间隔有长`a`，所以不可能连续遍历长度`d`。 
3. 初始化`dist[s] = 0`以及其他所有到无穷远的距离。 放`(0, s)`进入最小堆。 该堆总是为我们提供当前已知到达时间最短的城市。 
4. 当城市`u`随着时间的推移被提取`cur`，如果条目过时，则丢弃该条目，意思是`cur != dist[u]`。 否则，`cur`是已知的最早到达时间`u`。 
5. 对于从`u`到`v`,计算其周期`P = a+b`和其余的`r = cur % P`。 当前的干燥间隔可以准确地在以下情况下使用：

 [
 r+d\le a,
 ]

 这相当于`r <= a-d`。 

1. 如果该道路可以立即使用，则其候选到达时间为`cur+d`。 否则，计算下一个干燥间隔的开始时间：`cur-r+P`，并使用候选人到达时间`cur-r+P+d`。 
2. 如果该候选者小于`dist[v]`， 更新`dist[v]`并将新的对推入堆中。 这与普通 Dijkstra 中的松弛操作相同，只是有效边成本取决于当前时间。 
3.当城市`t`从堆中提取，返回其距离。 如果堆首先变空，`t`无法到达，答案是`-1`。 

正确性不变量是每个存储的`dist[v]`是迄今为止找到的最早到达时间，每次松弛都会计算从当前时间开始通过该特定道路的真正最早可能到达时间。 因为每条道路的最早到达函数都是不减的，所以晚到达城市永远不可能为下游创造更早的机会。 因此，当一个城市的最小距离堆条目最终确定时，没有任何未探索的路线可以击败它。 这正是 Dijkstra 需要的属性，所以最终的距离`t`是最优的。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m, s, t = map(int, input().split())

    graph = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v, a, b, d = map(int, input().split())

        # If d > a, there is no dry interval long enough
        # to traverse this road.
        if d <= a:
            graph[u].append((v, a, b, d))
            graph[v].append((u, a, b, d))

    INF = 10**30
    dist = [INF] * (n + 1)
    dist[s] = 0

    pq = [(0, s)]

    while pq:
        cur, u = heapq.heappop(pq)

        if cur != dist[u]:
            continue

        if u == t:
            print(cur)
            return

        for v, a, b, d in graph[u]:
            period = a + b
            rem = cur % period

            if rem <= a - d:
                # Enough dry time remains in the current period.
                nd = cur + d
            else:
                # Wait for the next period to start.
                nd = cur - rem + period + d

            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    print(-1)

if __name__ == "__main__":
    solve()
```邻接列表仅包含可用的道路。 移除道路`d > a`是安全的，因为每个干燥间隔都有精确的长度`a`，无论属于哪个时期。 

对于一条可用的道路，`period = a + b`描述了一个完整的天气周期。 表达式`cur % period`告诉我们当前时间位于该周期内的哪个位置。 道路已干，剩下的最多`a`，但交叉需要`d`连续的单位，所以实际情况是`rem + d <= a`，实施为`rem <= a - d`。 

等待计算值得特别注意。 如果当前的余数是`rem`，当前周期开始于`cur - rem`。 因此，它的下一个开始是`cur - rem + period`。 添加`d`等待后给出最早到达时间。 这避免了单个时间单位或时间段上的任何循环。 

Python 整数具有任意精度，因此潜在的较大到达时间不会溢出。 最大答案可能比`32`位整数限制，因为许多道路和等待时间可以累积。 

早返时`t`弹出对于 Dijkstra 是有效的，因为堆条目是按非递减距离顺序处理的。 在那一刻，弹出的距离就是最终的。 

## 工作示例

 提供的示例是```
3 2 1 3
1 2 3 4 1
2 3 2 3 2
```对于第一条路，`a=3`,`b=4`，所以它的周期是`7`。 萨姆开始时间`0`，其中余数是`0`，并且可以立即过马路。 

| 流行城市| 当前时间 | 边缘 | 剩余| 行动| 新品上市 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 |`1 -> 2`|`0 mod 7 = 0`| 立即交叉|`1`|
 | 2 | 1 |`2 -> 3`|`1 mod 5 = 1`| 立即交叉|`3`|
 | 3 | 3 | 目的地 | | 停止|`3`|

 这个直接跟踪似乎给出了`3`，但它揭示了间隔解释中的一个关键细节。 降雨间隔为`[a+k(a+b), (k+1)(a+b)]`，所以干燥间隔为`[k(a+b), a+k(a+b)]`。 对于第二条路，`a=2`,`b=3`,`d=2`，所以从时间开始`1`并按时完成`3`无效，因为下雨时间开始`2`。 山姆必须等到时间`5`，然后穿过并到达`7`。 

因此，正确的轨迹是：

 | 流行城市| 当前时间 | 边缘 | 剩余| 行动| 新品上市 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 |`1 -> 2`|`0`| 立即交叉|`1`|
 | 2 | 1 |`2 -> 3`|`1`| 等到`5`|`7`|
 | 3 | 7 | 目的地 | | 停止|`7`|

 答案是`7`，匹配样本。 该示例说明了为什么仅检查道路当前是否干燥是不够的。 整个遍历必须适合剩余的干燥部分。 

再举一个例子，考虑一条道路，其遍历正好填充干区间：```
2 1 1 2
1 2 3 5 3
```这里的时期是`8`，道路干燥`0`通过`3`，并且交叉恰好需要`3`。 

| 流行城市| 当前时间 | 剩余| 状况 | 到达 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 |`0`|`0 <= 3-3`|`3`|
 | 2 | 3 | 目的地 | |`3`|

 结果是`3`。 中的平等`rem <= a-d`这就是允许在下雨时准确到达的原因。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O((n+m) log n)`| 每个可用边缘从每个端点开始松弛，堆操作需要对数时间 |
 | 空间|`O(n+m)`| 图、距离数组、优先级队列需要线性空间 |

 和`100000`城市和`200000`道路上，该算法每次松弛仅执行对数数量的堆操作，而不是重复扫描整个图。 该图本身与输入大小呈线性关系，因此这符合约束的预期规模。

 ## 边缘情况

 第一个边缘情况是一条无法使用的道路。 为了```
2 1 1 2
1 2 3 5 4
```每个干燥间隔都有长度`3`，但交叉需要`4`时间单位。 预处理条件`d <= a`失败，因此从邻接列表中省略该边。 优先级队列仅包含城市`1`，和城市`2`永远不会达到。 算法打印`-1`。 

第二个边缘情况是雨开始或结束时的平等。 为了```
2 1 1 2
1 2 3 5 3
```初始余数为`0`和`a-d`也是`0`。 条件`rem <= a-d`成功了，所以 Sam 及时进入`0`并准时到达目的地`3`。 答案是`3`。 使用严格的不等式会错误地拒绝这条路径。 

第三种边缘情况是在一段时期的多雨时期出现的。 考虑```
3 2 1 3
1 2 1 2 1
2 3 2 3 2
```第一条路有句号`3`和干燥间隔长度`1`。 山姆穿越了时间`0`到时间`1`。 对于第二条路，周期为`5`其干燥间隔为`[0,2]`。 到达时间`1`正好留下一个单位的干燥时间，但穿越需要`2`， 所以`rem=1 > a-d=0`。 该算法等待直到下一个周期在时间开始`5`，交叉直到时间`7`，并到达目的地`7`。 

第四个边缘情况是新时期的开始。 假设一条路有`a=3`,`b=5`， 和`d=2`，山姆准时到达`8`。 其周期为`8`， 所以`8 % 8 = 0`。 该算法认识到`0 <= 3-2`并允许立即出发。 这很重要，因为降雨间隔的终点也是下一个干燥间隔的开始。 

最后一个边缘情况是无法到达的目的地。 和```
3 1 1 3
1 2 1 1 1
```城市`3`没有事故道路。 Dijkstra 探索包含城市的组件`1`，然后堆变空而不提取城市`3`。 算法打印`-1`，而不是将非常长的等待时间与实际可达性混淆。
