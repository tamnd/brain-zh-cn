 ## 解决方案
 ## 问题理解

 我们有一个无向图，其顶点是城市，边是道路。 山姆开始在城市`s`在某个时间`0`并想要到达城市`t`尽早。 每条道路都有自己的重复天气时间表。 如果一条道路有参数`a`,`b`， 和`d`，则其周期为`P = a + b`。 每个时期，道路不时干燥`Pk`通过`Pk + a`，并且有雨`Pk + a`通过`P(k + 1)`。 山姆可以在城市里自由地等待，但在穿过道路时`d`以时间为单位，整个遍历必须位于一个干区间内。 

任务是计算最早到达时间`t`， 或者`-1`如果不存在可用的路线。 这些道路没有方向，因此无论 Sam 使用道路的方向如何，都适用相同的时间表。 

该图最多有`100000`城市和`200000`道路。 在这个大小下，检查所有可能路径的算法是没有希望的，因为简单路径的数量已经是指数级的。 甚至一个`O(nm)`图算法在这种规模上太昂贵了，所以我们需要一个近线性或`O(m log n)`方法。 的价值观`a`,`b`， 和`d`可以达到`10^9`，并且等待可能会在多条道路上累积，因此实现还必须处理远大于 32 位整数的时间。 Python 整数自动适合这种情况。 

有几个边界，粗心的实施可能会失败。 首先，道路只有在以下情况下才可用：`d <= a`。 例如，```
2 1 1 2
1 2 1 1 2
```具有长度的干区间`1`，但这条路需要`2`交叉单位，所以答案是`-1`。 将道路视为具有平均行驶时间或仅检查出发时刻道路是否干燥将错误地允许该道路。 

第二个边界是 Sam 可以在干燥间隔开始时准确开始，并在干燥间隔结束时准确结束。 例如，```
2 1 1 2
1 2 2 3 2
```有干燥间隔`[0, 2]`，所以从时间遍历`0`到时间`2`是有效的，答案是`2`。 严格的不等式，例如`departure + d < a`会错误地拒绝这条路线。 

当山姆到达道路时，正好下雨了，第三个边界出现了。 考虑```
3 2 1 3
1 2 2 3 2
2 3 2 3 1
```第一条路可以从`0`到`2`。 时`2`，第二条路开始下雨，所以 Sam 无法启动它。 下一个干燥间隔开始时间`5`，给出到达时间`6`。 正确的输出是`6`。 仅检查出发时间与干间隔并忘记整个遍历的公式将错误地产生`3`。 

最后，如果`s == t`，Sam 已经到达目的地，所以答案是`0`，即使没有道路。 

## 方法

 直接的暴力解决方案可以枚举从`s`到`t`，模拟该路线各路段的天气情况，并保留最早到达时间。 这是正确的，因为每个可行的旅程都对应于某个图形路径，并且模拟固定路径告诉我们其最早可能的遍历时间。 问题在于路径的数量。 即使对于稀疏图，分层图也可以包含`2^(n/2)`独特简单`s`到`t`路径。 如果每条路径都经过`Theta(n)`工作来模拟，最坏的情况是`Theta(n * 2^(n/2))`操作，远远超出了可以处理的范围`n = 100000`。 

有用的观察是，当山姆到达一座城市时，我们不需要记住他的整个历史。 假设他在某个时间到达一个城市`x`。 对于任何一条外出道路，都有一个唯一确定的他可以开始穿越该道路的最早时间。 在城市中等待的时间永远不会比最早的可行出发时间更早到达另一个终点。 

对于一条路，让`P = a + b`并让`r = x mod P`。 如果`d > a`，这条路永远无法被遍历，因为每个干燥间隔都只是`a`单位长。 否则，Sam 可以立即离开`r + d <= a`。 如果该条件失败，他必须等到下一个干燥间隔开始，即`x - r + P`，然后花费`d`路上的单位。 

这给出了需要恒定时间的时间相关的边缘松弛。 更重要的是，由此产生的最早到达函数是先进先出的：晚到达一个城市永远不会让我们走同一条路更早到达另一个端点。 在可以立即遍历的部分内，到达时间随着起始时间而增加。 一旦遍历不再适合，所有这些起始时间都会等待相同的下一个干燥间隔，产生平坦部分，然后函数再次上升。 因此，普通 Dijkstra 的贪婪选择仍然有效。 

蛮力方法之所以有效，是因为每条路径都可以被精确评估，但会失败，因为路径太多。 先进先出属性让我们可以将到达同一城市的所有路径折叠成一个状态，即最早到达时间。 然后，我们可以使用 Dijkstra 算法，用恒定时间函数替换固定边权重，计算通过该道路的最早合法到达时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |`Theta(n * 2^(n/2))`在稀疏分层图中 |`O(n + m)`加上递归/路径状态 | 太慢了 |
 | 最佳 |`O((n + m) log n)`|`O(n + m)`| 已接受 |

 ## 算法演练

 1. 建立一个包含双向每条道路的邻接表。 对于每条道路，存储其参数`a`,`b`， 和`d`，因为任一端点的天气时间表都是相同的。 
2. 初始化`dist[s] = 0`以及其他所有到无穷远的距离。 放`(0, s)`进入最小堆。 堆总是为我们提供当前已知最早到达时间最小的城市。 
3.当城市`u`随着时间的推移从堆中删除`cur`，忽略该条目，如果`cur`大于`dist[u]`。 这样的条目是陈旧的，因为后来的放松已经找到了更好的方式来达到`u`。 
4. 对于从`u`到`v`，首先计算其周期`P = a + b`。 如果`d > a`，跳过这条路，因为没有足够长的干间隔来包含遍历。 
5. 否则计算`r = cur % P`。 如果`r + d <= a`，Sam可以立即进入道路，因此候选到达时间为`cur + d`。 
6.如果`r + d > a`，当前干燥间隔太短。 Sam 等待下一个周期开始于`cur - r + P`，然后穿过道路，让候选人到达`cur - r + P + d`。 
7. 如果该候选者小于`dist[v]`， 更新`dist[v]`并推`(candidate, v)`到堆中。 松弛与普通 Dijkstra 中的作用完全相同，只是边的有效行进时间取决于当前时间。 
8. 一旦堆为空，输出`dist[t]`如果是有限的，否则输出`-1`。 我们也可以尽快停止`t`以其当前距离弹出，因为堆保证未来状态的到达时间不会更小。 

### 为什么它有效

 不变的是，每当一个城市`u`被永久地从堆中提取，`dist[u]`是 Sam 可以到达的最早时间`u`。 对于每条外出道路，松弛计算在给定到达时间的情况下到达其另一个端点的最早可能到达时间`u`。 道路的到达功能是先进先出，所以到达`u`较晚的时间不能产生通过该路较早到达的时间。 因此，通常的 Dijkstra 论点适用：在提取最小的暂定到达时间后，没有任何未被发现的路线可以更早到达该城市。 在所有松弛中重复此操作可以给出每个可到达城市的真正最早到达时间，包括`t`。 

## Python 解决方案```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def solve():
    n, m, s, t = map(int, input().split())

    graph = [[] for _ in range(n)]

    for _ in range(m):
        u, v, a, b, d = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append((v, a, b, d))
        graph[v].append((u, a, b, d))

    dist = [INF] * n
    dist[s - 1] = 0

    pq = [(0, s - 1)]

    while pq:
        cur, u = heapq.heappop(pq)

        if cur != dist[u]:
            continue

        if u == t - 1:
            print(cur)
            return

        for v, a, b, d in graph[u]:
            if d > a:
                continue

            period = a + b
            r = cur % period

            if r + d <= a:
                arrive = cur + d
            else:
                arrive = cur - r + period + d

            if arrive < dist[v]:
                dist[v] = arrive
                heapq.heappush(pq, (arrive, v))

    print(-1)

if __name__ == "__main__":
    solve()
```邻接表将每条无向道路存储两次，这使得无论遍历方向如何，每个松弛都是相同的。 每个存储的元组恰好包含计算下一次合法遍历所需的参数。 

支票`d > a`立即消除不可能的道路。 干燥间隔有长度`a`，所以遍历时间不会超过`a`可以装在里面。 

表达式`cur % period`给出 Sam 在当前天气周期内的位置. 什么时候`r + d <= a`，整个遍历过程适合在下雨之前进行。 允许相等，因为干燥间隔的端点有效。 

当遍历不适合时，`cur - r`是当前周期的开始，所以`cur - r + period`是下一个时期的开始。 添加`d`等待后给出最早到达时间。 该公式避免了任何浮点运算并处理任意大小的时间。 

优先级队列采用惰性删除。 在逐渐找到更好的路线后，一个城市可能会被插入多次，因此每当其时间与当前时间不同时，提取的对就会被忽略`dist[u]`。 

最大可能答案可能比`10^9`，因为许多道路都会贡献大量的出行和等待时间。 Python 的任意精度整数无需任何特殊处理即可避免溢出。

 ### 示例 1

```对于第一条路，`P = 7`干燥间隔为`[0, 3]`。 开始时间`0`, 一次遍历结束时间`1`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |`O((n + m) log n)`| 每条路从两个端点都放宽，堆操作成本`O(log n)`|
 | 空间|`O(n + m)`| 邻接表包含`2m`定向条目，而距离和堆使用`O(n + m)`空间|

 和`n <= 100000`和`m <= 200000`，该算法对每个边缘松弛执行恒定量的算术，并使用二叉​​堆作为优先级队列。 这是标准比例，其中`O(m log n)`是实用的，而枚举路径或重复扫描所有边缘则不可行。

 ## 边缘情况

 对于`s == t`，考虑确切的输入```
1 0 1 1
```优先队列以城市开始`1`在某个时间`0`。 由于它已经是目的地，算法立即打印`0`。 不需要边缘处理，道路的存在与否也无关紧要。 

对于无法使用的道路，请考虑```
2 1 1 2
1 2 1 1 2
```路有期`2`，干间隔长度`1`。 该算法看到`d = 2 > a = 1`并跳过道路。 目的地保持在无穷远，因此输出为`-1`。 这比尝试等待循环中的特殊位置要好，因为没有任何干间隔可以包含完整的遍历。 

对于精确的干边界遍历，请使用```
2 1 1 2
1 2 2 3 2
```时`0`,`r = 0`， 和`r + d = 2 = a`。 条件满足，所以 Sam 立即出发并准时到达`2`。 输出是`2`。 中的平等`r + d <= a`是必要的。 

要在下雨时准确到达，请使用```
3 2 1 3
1 2 2 3 2
2 3 2 3 1
```第一条路将山姆从`0`到`2`。 对于第二条路，其周期为`5`，所以在某个时间`2`我们有`r = 2`。 自从`r + d = 3 > a = 2`，当前的干区间不能包含遍历。 下一个干燥间隔开始于`5`, 给出到达`5 + 1 = 6`。 输出是`6`。 这解决了仅在出发时刻检查道路是否干燥的常见错误。 

对于大输入边界，一链`100000`每条道路都设置为的城市`a = b = d = 1`有一个特别简单的行为。 每条路都可以从精确的周期边界开始遍历，因此每条边都贡献一个单位，无需等待。 到达目的地的时间为`99999`。 Dijkstra 实现处理该图`O(n log n)`这种情况下的时间并使用线性图存储，这说明了为什么渐近复杂度适合最大约束。
