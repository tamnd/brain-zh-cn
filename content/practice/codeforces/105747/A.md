 ## 解决方案
 ## 问题理解

 该任务描述了一个非常简单的生产过程：每杯混合果汁恰好消耗一个芒果和一个橙子。 我们有两个数量，可用的芒果数量和可用的橙子数量，我们必须确定可以制作多少杯完整的果汁。 

每个玻璃杯同时受到两种成分的约束。 即使其中一种水果丰富，没有另一种水果就无法形成一杯酒，因此限制因素始终是配对过程中先用完的水果。 

输入由两个整数组成，表示芒果和橙子的可用数量。 输出是一个整数，表示可以生产的最大满果汁杯数量。 

约束允许的值最大为 10^9。 这立即排除了任何模拟一次消耗一杯的方法。 在最坏的情况下，线性模拟最多需要 10^9 次迭代，这远远超出了典型的时间限制。 因此，该问题需要在恒定时间内进行推理。 

当两个数量极度不平衡时，就会出现微妙的边缘情况。 例如，如果输入为 1 1000000000，即使有大量剩余的橙子，也只能生产一杯玻璃。 重复相减直到一个值达到零的天真的贪婪循环在逻辑上仍然会产生正确的答案，但在计算上是不可行的。 

## 方法

 蛮力策略会通过减少芒果和橙子的数量来重复形成一杯酒，直到其中一个变为零。 每次迭代对应于生产一杯玻璃，因此迭代次数等于答案。 

这种方法是正确的，因为它直接模拟问题陈述。 然而，在最坏的情况下，当 M 和 O 都是 10^9 时，将需要 10^9 次迭代。 每次迭代都会执行恒定的工作，因此总复杂度变为 O(min(M, O))，这对于典型的执行约束来说太慢了。 

关键的观察结果是，每个操作恰好消耗两种资源中的一个单位。 因此，当一种资源耗尽时，该过程恰好停止。 完成操作的次数完全由两个初始值中较小的一个决定。 我们可以直接将结果计算为两个数字中的最小值，而不是模拟逐步消耗。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(分钟(M, O)) | O(1) | O(1) | 太慢了|
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取代表芒果和橙子可用数量的两个整数。 这些值定义了我们可以执行配对操作的次数。 
2. 观察每个操作恰好消耗一个芒果和一个橙子，因此操作总数受到资源较小者的限制。 
3. 计算两个值中的最小值。 这直接对应于一种成分用完之前可以形成的完整玻璃杯的数量。 
4. 输出计算出的最小值作为最终答案。 

### 为什么它有效

 在制作果汁的每一步中，两种资源都会减少一个单位。 这意味着两个数量之间的差异在整个过程中保持恒定。 最终，其中一个首先达到零，此时无法形成更多的完整对。 因此，成功操作的总数正是较小资源的初始计数，因为它从一开始就是瓶颈。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    data = input().strip().split()
    m = int(data[0])
    o = int(data[1])
    return str(min(m, o))

if __name__ == "__main__":
    sys.stdout.write(solve())
```该解决方案从输入中读取两个整数，将它们转换为数字形式，然后直接计算它们的最小值。 结果以字符串形式返回以进行输出。 逻辑完全包含在单个计算中，完全避免了循环。 关键的实现细节是确保正确解析输入和处理空格，因为输入是在单行上提供的。

 两种资源同时耗尽，因此形成所有 4 个可能的对。 这表明了平衡的情况，没有资源被浪费。

 ## 边缘情况

 对于极度倾斜的输入，例如`1 1000000000`，一个简单的循环将尝试十亿次迭代。 最优解而是直接计算`min(1, 1000000000)`并立即返回 1，避免任何模拟。 

对于平衡大输入，例如`1000000000 1000000000`，两种资源一起耗尽。 该算法正确返回完整值，没有任何溢出或迭代错误的风险，因为它仅依赖于恒定时间比较而不是重复减法。
