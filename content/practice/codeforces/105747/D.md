 ## 解决方案
 ## 问题理解

 我们得到一个整数数组，并要求检查长度至少为 2 的每个连续子数组。 对于每个这样的子数组，我们根据其大小及其两个最小元素计算一个值。 具体来说，对于子数组，我们获取其长度并将其乘以其中最小值和第二小值的总和。 任务是找到所有有效子数组中的最大此类值。 

因此，问题不在于求和或前缀查询，而在于识别每个区间内的一对小元素并将其与区间长度相结合。 困难来自于每个子数组都依赖于其内部顺序统计信息，并且我们需要第二最小值，这已经比标准范围最小值问题更加微妙。 

输入大小约束意味着所有测试用例的元素总数最多为二十万。 任何试图枚举所有子数组的解决方案都会考虑大约 N 平方的候选，这在最坏的情况下大约是 4 × 10^10 次操作，并且是完全不可行的。 即使 O(N^2 log N) 方法也太慢了。 

一个更微妙的约束是，答案取决于所有区间的全局最大值，因此我们不需要枚举每个位置的答案，只需确保考虑每个最佳区间形状。 这通常标志着单调结构或减少到仅考虑“关键”区间。 

一个天真的错误是假设最好的子数组总是包含全局最小值的子数组。 这是错误的，因为该公式取决于所选范围内的最小值和第二最小值。 另一个微妙的失败是假设扩展子数组总是会减少最小对的贡献，但这不一定正确，因为尽管值保持不变，但乘法长度却增加了。 

具体的反例是：

 数组：[5,1,4,2]

 子数组 [1, 4, 2] 的长度为 3，其两个最小值是 1 和 2，即 3 × 3 = 9。 

但是子数组 [1, 4] 给出 2 × 5 = 10，尽管它更短并且不包含相同的第三个元素，但它更大。 因此，最佳间隔不一定是最大的或以全局最小值为中心。 

这表明我们必须仔细跟踪范围内第二个最小值的形成位置，而不仅仅是最小值。 

## 方法

 直接强力方法检查每个子数组，扫描它以找到最小和第二小的值，并计算分数。 对于每个子数组，扫描需要 O(N)，并且有 O(N^2) 个子数组，导致每个测试用例的时间复杂度为 O(N^3)。 即使使用数据结构改进扫描以维持两个最小值，总体也会得到 O(N^2) ，当 N 在测试中达到 2 × 10^5 时，这仍然太大。 

关键的观察是停止考虑任意间隔，而是考虑第二个最小值的行为。 对于任何子数组，第二最小值由该区间内的两个特定元素确定：同一区间内的最小元素和严格大于它的最小元素。 这表明，对于第二小的元素的固定选择，我们只需要找到一个范围，该范围是允许内部存在更小的元素的边界值。 

一种更结构化的思考方式是固定子数组中第二个最小元素的位置。 假设我们选择一个索引 j 作为所选区间中第二个最小值的位置。 那么最小值必须来自 j 的任一侧，并且必须严格小于 A[j]，而区间中的所有其他元素必须至少为 A[j]。 这立即限制了区间边界：我们向左和向右延伸，直到遇到小于 A[j] 的元素，因为这些元素会违反 A[j] 为第二最小值的条件。

在这个受约束的段内，使用 A[j] 作为第二最小值的最佳子数组会将其与段中的最小值配对，并且我们希望最大化长度，因此我们在保留 A[j] 是第二小的约束的同时尽可能地扩展。 

这将问题简化为，对于每个索引 j，找到最远的有效区间，其中没有小于 A[j] 的元素阻止扩展，同时确保该区间内至少有一个小于 A[j] 的元素。 第二个要求意味着我们还需要 j 两侧最近的较小元素。 

这种结构自然是使用单调堆栈来处理的，该堆栈为每个位置计算左侧和右侧最近的严格较小的元素。 这些边界定义了最大分段，其中 A[j] 是第二小位置的最小候选。 在该段内，最小值的最佳伙伴就是段中严格小于 A[j] 的最小元素，如果需要，可以使用前缀/后缀预处理或段树查询来跟踪它。 

通过这些观察，我们不再枚举子数组。 相反，我们将每个索引评估为潜在的“第二最小锚点”，并在摊余常数时间内计算其周围的最佳间隔。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N^3) | O(N^3) | O(1) | O(1) | 太慢了 |
 | 最优（单调+边界扩展）| O(N) | O(N) | 已接受 |

 ## 算法演练

 1. 对于每个位置 j，将 A[j] 解释为某个最佳子数组中第二个最小值的候选值。 这是避免枚举所有区间的结构支点。 
2. 计算 j 左侧和 j 右侧最近的严格较小元素。 这些位置定义了最大间隔，其中 A[j] 可以充当第二最小值，而不会被预期结构之外的较小元素失效。 
3. 将 j 的有效窗口定义为两个最接近的较小元素之间的间隔。 在此窗口内，任何包含 j 且至少包含一个比 A[j] 小的元素的子数组都可以使用 A[j] 作为第二个最小值。 
4. 在该窗口内，确定严格小于 A[j] 的最小元素。 该元素将充当子数组的最小值，因为第二个最小值固定为 A[j]，因此最佳伙伴是最小的有效候选者。 
5. 将候选答案形成为（窗口长度）乘以（最小有效元素+ A[j]），并更新全局最大值。 
6. 对所有 j 重复此操作，注意确保仅考虑包含至少一个较小元素的有效窗口。 

这样做的原因是任何最佳子数组都必须具有明确定义的第二小元素，并且固定该元素唯一地确定子数组可以扩展的位置，而不会引入会改变第二最小标识的较小值。 单调堆栈边界确保每个此类有效配置通过其第二最小锚点被恰好考虑一次，并且不会错过任何有效间隔，因为每个子数组都恰好有一个位置可以作为该构造下的第二最小元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # nearest smaller to left
    left = [-1] * n
    st = []
    for i in range(n):
        while st and a[st[-1]] >= a[i]:
            st.pop()
        left[i] = st[-1] if st else -1
        st.append(i)
    
    # nearest smaller to right
    right = [n] * n
    st = []
    for i in range(n - 1, -1, -1):
        while st and a[st[-1]] > a[i]:
            st.pop()
        right[i] = st[-1] if st else n
        st.append(i)
    
    # prefix minimums
    pref = [10**18] * n
    cur = 10**18
    for i in range(n):
        cur = min(cur, a[i])
        pref[i] = cur
    
    # suffix minimums
    suff = [10**18] * n
    cur = 10**18
    for i in range(n - 1, -1, -1):
        cur = min(cur, a[i])
        suff[i] = cur
    
    ans = 0
    
    for j in range(n):
        l = left[j] + 1
        r = right[j] - 1
        
        if r - l + 1 < 2:
            continue
        
        # smallest element in [l, r] excluding A[j]
        best_min = min(pref[r], suff[l])
        if best_min >= a[j]:
            continue
        
        length = r - l + 1
        ans = max(ans, length * (best_min + a[j]))
    
    print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```该解决方案首先使用单调堆栈计算最近的较小边界。 这些边界保证在每个段内，没有小于所选锚点 A[j] 的元素出现在间隔之外，因此 A[j] 可以安全地充当第二个最小候选者。 

然后使用前缀和后缀最小值来在恒定时间内查询任何段中的最小元素。 这避免了需要线段树，同时仍然允许我们有效地提取每个锚点的最佳伙伴。 

每个指标被视为候选第二最小值，其最大有效区间被评估一次。 最终答案汇总了所有此类配置的最佳得分。 

## 工作示例

 考虑数组 [5, 1, 4, 2]。 

对于 j = 2（值 4），最近的较小边界给出 l = 1 和 r = 3。该段为 [1, 4, 2]。 该段中最小的元素是 1，第二小的候选元素是 4。该值变为 3 × (1 + 4) = 15。 

对于 j = 3（值 2），边界为 l = 1 和 r = 3。该段为 [1, 4, 2]。 最小的元素仍然是 1，因此值变为 3 × (1 + 2) = 9。 

| j | A[j] | 细分 | 分段中的最小值 | 长度| 分数 |
 | --- | --- | --- | --- | --- | --- |
 | 2 | 4 | [1,4,2]| 1 | 3 | 15 | 15
 | 3 | 2 | [1,4,2]| 1 | 3 | 9 |

 最大值来自于固定4作为第二最小锚点，展示了第二最小位置如何控制最优结构。 

第二个例子是[2,2,2]。 每个长度至少为 2 的子数组的最小值和第二最小值等于 2。最好的子数组是完整数组，给出 3 × (2 + 2) = 12，它可以被任何锚点捕获，因为所有位置都表现对称。

 ## 边缘情况

 一个微妙的情况是所有元素都严格增加。 在 [1, 2, 3, 4] 中，第二个最小值始终是所选区间中的第二个最小值，它往往来自左边界。 单调堆栈确保每个位置仍然获得有效段，并且前缀最小值正确识别最小伙伴。 

另一种情况是存在重复项。 在[3,3,1,3]中，相等的元素可能会干扰“严格更小”的假设。 在堆栈构造中使用非严格比较可确保相等的值不会错误地扩展段，从而违反第二最小排序。 

当所选锚点不存在有效伙伴时，就会出现边界情况，这意味着其段中的所有元素都大于或等于。 在这种情况下，支票`best_min >= a[j]`正确地丢弃配置，防止无效的子数组对答案做出贡献。
