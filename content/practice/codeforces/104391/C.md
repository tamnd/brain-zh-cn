 ## 解决方案
 ## 问题理解

 我们在数轴上得到一组区间，每个区间代表一座具有左端点和右端点的“山”。 当一个间隔完全位于另一个间隔内时，该间隔被视为另一个间隔的子级，这意味着它的左端点不小于且右端点不大于。 

根据这种包含关系，我们构建了一个有向结构，其中每个区间都指向严格包含在其中的所有区间。 间隔的分数定义为从该间隔开始并重复移动到任何包含的间隔的最长链的长度。 如果一个区间不包含其他区间，则其得分为 1。 

任务是计算每个间隔的分数，并报告所有间隔的最大分数。 

输入大小达到40万个区间，坐标高达10亿个。 任何将每个间隔与其他间隔进行比较的解决方案都会立即被排除，因为在最坏的情况下需要进行 10^11 次比较。 即使基于排序的 O(n^2) 策略或简单的图构建也太慢了。 

结构也不是任意的。 包含仅取决于具有单调条件的两个坐标：子项必须具有较大或等于的左端点和较小或等于的右端点。 这是一个二维支配关系，这表明问题实际上是关于有效查询和更新部分有序平面中的点。 

当许多间隔共享相同的左端点时，会出现微妙的边缘情况。 在这种情况下，包含仅依赖于右端点，并且如果不仔细处理等左组内的依赖关系，则通过单个坐标进行的简单排序很容易产生不正确的结果。 另一个极端情况是深度嵌套链，其中答案可以达到 O(n)，这使得在没有仔细排序的情况下递归不安全。 

## 方法

 一种直接的方法是显式构建包含图。 对于每个区间 i，我们检查每个区间 j，如果 j 位于 i 内部，则添加一条边。 然后我们在此图上运行 DFS 或 DP 来计算最长路径。 这是正确的，因为分数定义正是有向无环图中的最长路径。 问题是构造成本：检查所有对需要 O(n^2) 次比较，这远远超出了 n 为 400,000 时的限制。 

关键的观察是我们不需要显式的边缘。 对于每个区间，我们只需要知道其内部所有区间的最大 dp 值即可。 这将问题转化为对动态点集的范围查询，其中每个区间是一个点（L，R），我们希望查询 L_j ≥ L_i 且 R_j ≤ R_i 的所有点。 

这是一个二维支配问题。 如果我们通过减小 L 来对区间进行排序，那么在我们处理区间 i 的那一刻，所有具有较大 L 的区间都已被处理。 剩下的问题是有效处理 R 上的约束，可以使用压缩 R 坐标上的 Fenwick 树将其减少为前缀最大查询。 

然而，仅按 L 排序是不够的，因为区间可以共享相同的 L。在这种情况下，同一组内的区间可以基于 R 排序相互依赖。 这迫使我们单独处理 equal-L 组，在提交更新到全局结构之前确保组内转换的正确性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力配对检查 + DP | O(n^2) | O(n^2) | O(n^2) | O(n^2) | 太慢了 |
 | 排序扫描+带有分组处理的BIT | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 该解决方案依赖于按左端点降序扫描间隔，同时保持右端点上的最佳可达 dp 值。 

### 1.右端点坐标压缩

我们首先将所有 R 值压缩到较小的范围内。 这是必要的，因为 Fenwick 树需要连续的索引。 压缩保留了顺序，这是我们需要的唯一属性。 

### 2. 通过减小 L 对区间进行排序

 我们按 L 的降序对所有区间进行排序。L 较大的区间会被更早处理，确保当我们处理一个区间时，所有 L_j ≥ L_i 的可能候选者都已被看到，除了那些具有相等 L 的区间。 

这确立了全局依赖方向。 

### 3. 以相等的 L 组处理间隔

 所有具有相同左端点的间隔都一起处理。 在这样的组中，遏制仅取决于 R 值。 如果区间 j 的 R 小于或等于 i，则 j 可以是 i 的子级，但反之则不然。 

这意味着在一个组内，我们必须以递增的 R 顺序进行处理，以便在较大的间隔之前计算较小的间隔。 

### 4.维护两棵芬威克树

 我们使用全局芬威克树来存储所有先前处理组的结果。 这回答了涉及严格更大的 L 值的查询。 

我们还为当前组维护一棵临时 Fenwick 树。 这处理了共享相同 L 的区间之间的依赖关系。 

对于组中的每个间隔 i，我们将其 dp 值计算为 1 加上两个值的最大值：R ≤ R_i 的先前处理组中的最佳 dp，以及 R ≤ R_i 的同一组中较早元素中的最佳 dp。 

这正确地捕获了所有可能的孩子。 

### 5.更新结构

 计算出整个组的 dp 值后，我们将它们全部插入全局 Fenwick 树中。 这确保了未来的小组可以使用它们。 

### 6. 跟踪全局最大值

 在计算 dp 值时，我们保持看到的最大值，这就是最终的答案。 

### 为什么它有效

 在每一步中，全局芬威克树代表具有严格更大的 L、完全处理和固定 dp 值的所有区间。 组 Fenwick 树准确地表示通过增加 R 排序的当前 equal-L 块的前缀。每个有效的子关系都恰好属于这两个类别之一，因此对 dp 做出贡献的每个转换都被恰好考虑一次，并且不会引入无效转换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def update(self, i, v):
        while i <= self.n:
            if v > self.bit[i]:
                self.bit[i] = v
            i += i & -i

    def query(self, i):
        res = 0
        while i > 0:
            if self.bit[i] > res:
                res = self.bit[i]
            i -= i & -i
        return res

def main():
    n = int(input())
    seg = []
    rs = []

    for idx in range(n):
        l, r = map(int, input().split())
        seg.append((l, r, idx))
        rs.append(r)

    rs = sorted(set(rs))
    rid = {v: i + 1 for i, v in enumerate(rs)}

    seg.sort(key=lambda x: (-x[0], x[1]))

    fw_global = Fenwick(len(rs))
    dp = [0] * n

    i = 0
    ans = 0

    while i < n:
        j = i
        curL = seg[i][0]

        group = []
        while j < n and seg[j][0] == curL:
            group.append(seg[j])
            j += 1

        group.sort(key=lambda x: x[1])

        fw_local = Fenwick(len(rs))

        for l, r, idx in group:
            ri = rid[r]
            best = fw_global.query(ri)
            best = max(best, fw_local.query(ri))
            dp[idx] = best + 1
            fw_local.update(ri, dp[idx])

        for l, r, idx in group:
            fw_global.update(rid[r], dp[idx])
            if dp[idx] > ans:
                ans = dp[idx]

        i = j

    print(ans)
    print(*dp)

if __name__ == "__main__":
    main()
```Fenwick 树用作压缩右端点上的前缀最大结构。 全局结构累积来自已处理的左端点的结果，而本地结构则解决当前 equal-L 组内的依赖关系。 dp 转换始终是“最佳包围间隔 + 1”，通过前缀查询实现。 

排序顺序至关重要：减少 L 可确保正确的全局依赖方向，而增加组内的 R 可确保相同 L 包含的正确性。 

## 工作示例

 ### 示例 1

 输入间隔为：

 (9,13)、(11,13)、(7,11)、(1,9)、(2,6)、(3,8)、(6,7)

 通过递减 L 排序后，处理从 (11,13) 开始，然后是 (9,13)，依此类推。 

对于 (11,13)，不存在更大的 L 区间，因此 dp = 1。 

对于 (9,13)，它在全局结构中看到 (11,13)，但由于 11 ≥ 9 且 13 ≤ 13，它可以扩展它，给出 dp = 2。 

继续这个过程，最深的嵌套链通过 (1,9) → (2,6) → (6,7) 形成，在间隔 (9,13) 处产生最大深度 3。 

最终 dp 值与预期输出匹配：

 2 1 1 3 1 2 1

 该迹线证实，只有有效的遏制转换才会促进 dp 增长，并且不相关间隔之间不会发生交叉干扰。 

### 示例 2

 间隔：

 (1,3)、(1,6)、(1,5)、(1,1000)、(1,4)

 所有间隔共享相同的 L，因此所有内容都在单个组内解决。 

按 R 排序得出：

 (1,3)、(1,4)、(1,5)、(1,6)、(1,1000)

 我们从最小的 R 向上处理。 每个间隔都将所有较小的孩子视为潜在的孩子。 这会创建一个不断增加的 dp 值链：

 dp(1,3)=1

 dp(1,4)=2

 dp(1,5)=3

 dp(1,6)=4

 dp(1,1000)=5

 此示例隔离了组内处理的重要性。 如果没有它，equal-L 依赖关系将完全丢失。

 ## 边缘情况

 一种重要的边缘情况是所有间隔共享相同的左端点。 在这种情况下，整个答案仅取决于右端点的排序。 该算法通过按 R 对组进行排序并使用本地芬威克树来正确处理此问题，确保每个间隔都建立在较小的间隔之上。 

另一个边缘情况是严格增加嵌套链，如 [1,10]、[2,9]、[3,8]、[4,7]。 在这里，每个间隔都取决于前一个间隔。 全局 Fenwick 树正确传播 dp 值，因为每个间隔都是在所有较大的 L 间隔之后处理的，因此链是增量重建的。 

第三种边缘情况涉及不相交的区间，例如 [1,2]、[3,4]、[5,6]。 None 包含另一个，因此所有 dp 值都保持为 1。Fenwick 查询始终返回零，从而防止跨非重叠区域的意外传播。
