 ## 解决方案
 ## 问题理解

 城市是一个有向时间图。 每辆巴士都是一条边，有出发时间、到达时间以及出行当天存在的概率。 你从车站出发`0`在所有公交车出发之前，你需要最大化到达车站的概率`1`按时间`k`。 

困难来自于两个细节。 公交车可能会消失，只有在选择它之后你才会知道这一点。 此外，同一时间从同一个车站出发的公交车也不能全部进行测试，因为在一次尝试失败后，出发时刻就已经过去了。 

约束是主要提示。 最多可以有`10^6`公共汽车和`10^6`站，因此任何涉及随时间动态规划或重复图搜索的事情都是不可能的。 时间值可以大到`10^18`，因此我们无法迭代每个可能的时刻。 该算法必须仅处理给定的总线事件，这意味着大致线性或线性对数工作。 

一个常见的错误是将同时出发的巴士视为独立选择。 例如：```
2 2
1
0 1 0 1 0.5
0 1 0 1 0.5
```答案是`0.5`， 不是`0.75`。 您只能尝试一趟巴士。 另一个错误是当到达时间等于出发时间时允许转机。 如果一辆公共汽车恰好在另一辆汽车离开时到达，则该连接无效。 

## 方法

 暴力解决方案会尝试模拟所有可能的策略。 在每个车站和时间，它都会考虑所有可以乘坐的公交车，并递归计算最佳概率。 这是正确的，因为它探索了每一个可能的决定，但状态的数量是巨大的。 最多有`10^6`公共汽车和换乘链可以创造出指数级的多种可能策略。 

关键的观察是所有决策都可以及时向后处理。 在考虑巴士出发时间时`s`, 每趟巴士出发时间为`s`已经处理了。 因此我们已经知道了这辆公交车到达目的地后成功的最佳概率。 

让`dp[v]`意思是：如果我们在车站`v`在当前处理时间所有出发后，最终到达机场的最大概率是多少？ 

对于公共汽车`a -> b`准时离开`s`，如果我们尝试一下，概率是：```
p * dp[b] + (1 - p) * dp[a]
```第一项是公交车运行的情况。 第二项是失败的情况，我们被困在车站`a`出发时刻过去后。 

有必要将相同发车时间的公交车放在一起处理。 每个候选者都必须使用旧值`dp[a]`，因为失败的尝试不能同时由另一条总线跟随。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 大| 太慢了|
 | 向后扫 | O(m log m) | O(n + m) | 已接受 |

 ## 算法演练

 1. 初始化`dp[1] = 1`因为已经到达机场就意味着成功。 每个其他站都以概率开始`0`。 
2. 将所有公交车按照出发时间降序排列。 最晚出发的巴士将首先处理，因为其目的地无法使用任何较晚的巴士。 
3. 对于共享相同出发时间的每组公共汽车，使用当前的计算每个可能的尝试`dp`价值观。 
4. 对于有概率的总线`p`,存储候选值`p * dp[destination] + (1 - p) * dp[start]`。 
5. 对整个时间组进行评估后，用该组中的最佳候选更新起始站。 
6. 所有总线处理完毕后，`dp[0]`是初始状态的最优概率。 

不变的是在处理出发时间之前`s`,`dp[v]`已经包含仅使用之后出发的巴士的最佳概率`s`。 巴士出发时间为`s`只需要来自其目的地的未来信息，该信息已经可用。 一起处理相同的出发时间可以保留此时只能尝试一辆公交车的规则。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    m, n = map(int, input().split())
    k = int(input())

    buses = []

    for _ in range(m):
        a, b, s, t, p = input().split()
        buses.append((int(s), int(a), int(b), float(p)))

    buses.sort(reverse=True)

    dp = [0.0] * n
    dp[1] = 1.0

    i = 0
    while i < m:
        time = buses[i][0]
        best = {}

        while i < m and buses[i][0] == time:
            _, a, b, p = buses[i]
            value = p * dp[b] + (1.0 - p) * dp[a]

            if a not in best or value > best[a]:
                best[a] = value

            i += 1

        for a, value in best.items():
            if value > dp[a]:
                dp[a] = value

    print("{:.10f}".format(dp[0]))

if __name__ == "__main__":
    solve()
```排序顺序是实现的核心。 公交车准时到达`t`总是需要时间来回答`t`，这意味着每辆发车时间大于`t`必须已经被处理过。 

团体更新也是必不可少的。 更新中`dp`在看到单个公共汽车后立即允许同一出发时间的另一辆公共汽车在尝试失败后错误地使用改进的值。 保留候选人`best`防止这种情况发生。 

Python 浮点精度在这里就足够了，因为所需的误差仅为`10^-6`。 时间值从不用于算术，因此它们的大小不会产生溢出问题。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m log m) | 排序占主导地位； 每条总线都被处理一次|
 | 空间| O(n + m) | 存储公交车和每个车站的一个概率 |

 对于一百万条总线，线性扫描很容易管理，并且在慷慨的内存限制下对数排序因子是可以接受的。 

## 工作示例

 对于第二个样本：```
4 2
2
0 1 0 1 0.5
0 1 0 1 0.5
0 1 1 2 0.4
0 1 1 2 0.2
```首先处理最新的两辆巴士。 

| 出发时间 | 公交车概率 | 处理后的 dp[0] |
 | --- | --- | --- |
 | 1 | 0.4, 0.2 | 0.4 | 0.4
 | 0 | 0.5, 0.5 | 0.7 | 0.7

 时`1`，最佳选项给出概率`0.4`。 时`0`，尝试第一辆总线成功的概率`0.5`，失败就留下了乘坐稍后巴士的机会。 结果是：```
0.5 + 0.5 * 0.4 = 0.7
```与示例输出匹配。
