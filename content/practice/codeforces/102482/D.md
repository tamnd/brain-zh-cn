 # 问题理解

 我们有 n 个居民，每个居民都从一颗宝石开始。 d 晚后，每晚都会选择并分裂出一颗现有宝石，因此宝石总数变为 n+d。 分裂过程是随机的，但问题不是要求一种可能的最终状态。 它要求最终拥有最多收藏品的 r 居民拥有的宝石的预期数量。 

一个有用的第一个观察是每个有效的最终分布的可能性都是相等的。 最终分布可以描述为 n 个正整数，其总和为 n+d。 随机分裂过程为每个这样的分布提供相同的概率，因此问题变成了正整数组合的计数问题。 

约束 n,d ≤ 500 排除了任何枚举分布的情况，因为可能的分布数量是一个增长极快的二项式系数。 即使是尝试各种方法来分配 d 个额外宝石的方法，在 d 达到 500 之前很久也是不可能的。在 n 和 d 维度上的动态程序是合适的，因为只有大约 250000 种可能的状态，并且在这些状态下转换必须保持接近线性。 

一个微妙的情况是，每个居民都是最富有的人。 例如，输入`3 5 3`意味着我们想要所有三个居民，所以答案只是宝石总数 8。始终假设某些人被排除在顶部组之外的解决方案可能会错误地丢失宝石。 

另一种边界情况是当用一颗宝石移除居民后，重复中 d 为零。 例如，输入`2 1 1`有可能的分布`(2,1)`和`(1,2)`，所以预期答案是 1.5。 粗心的递归允许无效的负数额外宝石将产生不正确的状态。 

# 方法

 蛮力方法是生成所有可能的宝石最终分布，对 n 值进行排序，然后添加最大的 r 值。 它是正确的，因为每个分布都有相同的概率，因此对所有分布进行平均即可得到期望值。 问题在于分布的数量。 有`C(n+d-1,d)`可能的正组合，对于接近 500 的值来说已经是巨大的了。生成和排序每个分布的工作是完全不可行的。 

关键的观察是停止考虑单个分布，而是计算分布组。 令 S(n,d) 为包含 n 个居民和 d 个额外宝石的所有有效分布中前 r 个宝石的总和。 这种分布的数量是`C(n+d-1,d)`，所以最终的答案是`S(n,d)`除以这个计数。 

考虑每个居民的第一颗宝石。 每个有效的分配都会将这些第一颗宝石中的r恰好贡献给最富有的r个人。 剩余的贡献仅来自拥有超过一颗宝石的居民。 假设恰好有 g 个居民只有一颗宝石。 移除这些 g 人并从每个剩余居民中移除一颗宝石会留下一个较小的实例`n-g`居民和`d-n+g`额外的宝石。 这给出了较小状态的重现。

 # 算法演练

 1. 使用帕斯卡三角形预先计算最多 1000 的二项式系数。 需要这些值是因为可能的分布数量是一个组合值。 
2. 定义`dp[n][d]`作为最富有的 r 居民在 n 居民和 d 额外宝石的所有有效分配中的总贡献。 具有负 d 的无效状态贡献为零。 
3. 处理状态`n <= r`分别地。 每个居民都属于最富有的群体，因此每个分配的贡献就是`n+d`宝石。 
4. 对于其他每个州，从每个居民拥有的第一颗宝石的贡献开始。 有`C(n+d-1,d)`分布，并且第一个宝石在每个宝石中都贡献了 r 个宝石，给出`r * C(n+d-1,d)`。 
5. 尝试所有可能的 g 个居民中恰好拥有一颗宝石。 选择其中的 g 个居民`C(n,g)`方式。 剩余的居民在移除第一批宝石后形成较小的分布，因此添加`C(n,g) * dp[n-g][d-n+g]`。 
6. 划分`dp[n][d]`通过可能的分布的数量来获得期望值。 

递归背后的不变量是每个状态都代表该状态所有可能分布的答案之和。 第一个宝石和额外宝石之间的划分是精确的：第一个宝石占不可避免的基础贡献，而所有剩余的宝石属于较小的有效实例。 由于每个分布都根据拥有一颗宝石的居民数量精确计算一次，因此重复计算不会重复计算或遗漏任何情况。 

# Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, d, r = map(int, input().split())

    limit = n + d + 5
    comb = [[0] * (limit + 1) for _ in range(limit + 1)]
    for i in range(limit + 1):
        comb[i][0] = comb[i][i] = 1
        for j in range(1, i):
            comb[i][j] = comb[i - 1][j - 1] + comb[i - 1][j]

    dp = [[0.0] * (d + 1) for _ in range(n + 1)]

    for people in range(1, n + 1):
        for extra in range(d + 1):
            if people <= r:
                dp[people][extra] = (people + extra) * comb[people + extra - 1][extra]
            else:
                total = r * comb[people + extra - 1][extra]
                for single in range(people + 1):
                    remain_extra = extra - people + single
                    if remain_extra < 0:
                        continue
                    if people - single == 0:
                        continue
                    total += comb[people][single] * dp[people - single][remain_extra]
                dp[people][extra] = total

    ways = comb[n + d - 1][d]
    print("{:.10f}".format(dp[n][d] / ways))

if __name__ == "__main__":
    solve()
```组合表存储分布的精确计数。 Python 整数是任意精度的，因此中间值不会溢出。 

动态规划表通过增加居民数量来填充。 每次转变都会导致居民减少，所以当`dp[people][extra]`计算出来，所有需要的较小状态都已经存在。 

条件`remain_extra < 0`删除不可能的状态，从所有非单身居民中移除第一颗宝石将需要比现有更多的额外宝石。 剩余居民为零的情况由`people <= r`仅当它是有效的顶级组计算时才规则，因此转换会跳过空状态。

 # 边缘情况

 对于`n=1`，顶部组始终包含唯一的居民。 复发率达到`n <= r`基本情况并返回宝石总数，即`1+d`。 

为了`r=n`，每个人都被计算在内，所以预期的答案总是`n+d`。 基本情况避免了不必要的递归并直接返回正确的总贡献。 

对于许多居民都拥有一颗宝石的分布，过渡为`g`单宝石居民单独处理它们。 例如，`2 1 1`有两种可能的最终状态，并且两者都通过相同的循环进行计数，而不是假设唯一的最富有的居民。 

对于较大的值，例如`500 500 250`，分布的数量很大，但算法从不单独创建它们。 它只存储它们的总贡献，这就是解决方案保持在限制范围内的原因。
