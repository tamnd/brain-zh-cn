 ## 解决方案
 ## 问题理解

 我们有一个相互连接的国家网络，该网络形成一棵树，这意味着每一对国家之间都有一条路径。 每条道路都有通过它的每支军队的成本。 国家`i`开始于`xi`军队和需求`yi`使军队满意。 满足所有要求后，额外的军队可以留在任何地方。 

任务是选择军队调动，使每个国家达到其所需的数量，同时总的旅行成本尽可能小。 由于每支通过道路的军队都要支付道路成本，因此输出是所有移动成本的最小可能总和。 

主要限制是树的大小。 对于多达 250,000 个国家，算法不可能检查每一种可能的行动或尝试所有的军队任务。 即使是一个粗略的算法`O(n * number_of_armies)`行动规模太大，因为军队总数可达100万。 该解决方案只需处理每个国家和每条道路恒定的次数，这指向线性树算法。 

有界的军队总数对于某些可能的解决方案很有用，但国家数量足够大，单独存储每支军队或模拟运动不太适合。 道路形成一棵树的事实是关键的结构属性，因为每条道路都将世界精确地分成两个独立的侧面。 

对于一个在同一子树中同时具有传入和传出需求的国家来说，粗心的解决方案可能会失败。 例如：```
2
1 2 10
5 3
0 4
```第一个国家有 2 支军队剩余，第二个国家需要 4 支军队。 正确答案是 20，因为两支军队必须穿过唯一的道路，而每支军队的成本为 10。仅考虑单个国家的解决方案可能会认为第一个国家可以满足第二个国家的要求，而不考虑剩余的赤字金额。 

另一个边缘情况是树的根有盈余或赤字。 例如：```
1
5 3
```正确答案是0。没有地方可以调动军队，而国家已经有足够的军队了。 假设所有盈余必须从根部向上流动的解决方案会错误地增加成本。 

最后一个棘手的情况是包含短缺和额外军队的子树。 例如：```
3
1 2 7
2 3 4
0 2
5 1
0 3
```包含节点 2 和 3 的子树的总盈余为 0，因为节点 2 有四支额外军队，节点 3 还需要三支军队，而节点 2 本身需要一支。 唯一需要的移动是一支军队从节点 2 到节点 3，成本为 4。仅考虑总子树平衡而忽略内部平衡的解决方案会高估成本。 

## 方法

 直接的方法是尝试反复将军队从拥有额外军队的国家转移到缺乏军队的国家。 由于该图是一棵树，因此任何两个国家之间的距离很容易计算。 对于每支失踪的军队，我们都可以找到附近的剩余军队并将其沿着路径移动。 这是正确的，因为每支军队最终都必须从盈余地点前往赤字地点。 

问题是工作量。 军队数量最多可达 1,000,000 人，每次军队移动可能需要走一条包含最多 250,000 条道路的路径。 模拟可以达到周围`10^11`最坏情况下的边缘遍历，远远超出了极限。 

改变问题的观察是，每支军队的确切身份并不重要。 考虑任何道路。 移除那条路会将树分成两个部分。 如果道路下方的部队数量超过其需要，则所有多余的军队都必须穿过该道路才能离开。 如果它需要的军队比现有的多，那么缺少的军队就必须穿过那条路才能进入。 没有替代路线，因为图是一棵树。 

因此，越过一条边的军队数量完全取决于该边一侧的总盈余或赤字。 我们只需要计算子树平衡。 

让`balance[i] = xi - yi`。 正值意味着子树有额外的军队，负值意味着它需要军队。 在深度优先遍历期间，我们计算每个子树中的余额总和。 对于每个子边，子树子树总和的绝对值告诉我们有多少军队必须穿过该边。 乘以边缘成本即可得出该道路的贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(总军队 × n) | O(n) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 构建树并将每个国家的初始余额存储为`xi - yi`。 正余额代表可以离开国家的军队，而负余额代表必须到达的军队。 
2. 以任意国家为树根并执行深度优先遍历。 在遍历过程中，计算每个子树的总余额。 

根的选择不会影响答案，因为每条边都只计算一次，并且边成本仅取决于通过删除它而创建的两条边。 
3.从子子树返回其父子树时，添加`abs(child_balance) * edge_cost`到答案。 

子子树要么发送`child_balance`军队向上或接收`-child_balance`军队向下。 这条道路必须能够容纳那么多军队，因为两侧之间没有其他连接。 
4. 将子级的余额添加到父级的余额中，并继续，直到处理完整个树。 

root的最终余额不需要移动，因为声明保证军队总数足以满足所有要求。 

### 为什么它有效

 对于每条边，树结构强制该边两侧之间的所有交互都通过该边。 子树内所需的最终军队数量是固定的，因此穿过其唯一连接的净数量也是固定的。 遍历计算每个边的精确数量，并为不可避免的移动收取尽可能小的成本。 由于每条道路的贡献都是独立强制的，因此所有贡献的总和就是全局最优值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    graph = [[] for _ in range(n)]
    
    for _ in range(n - 1):
        u, v, c = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append((v, c))
        graph[v].append((u, c))
    
    balance = [0] * n
    for i in range(n):
        x, y = map(int, input().split())
        balance[i] = x - y
    
    ans = 0
    stack = [(0, -1, 0)]
    order = []
    
    while stack:
        u, p, state = stack.pop()
        if state == 0:
            stack.append((u, p, 1))
            for v, c in graph[u]:
                if v != p:
                    stack.append((v, u, 0))
        else:
            order.append((u, p))
    
    for u, p in order:
        if p != -1:
            pass
    
    parent = [-1] * n
    parent_cost = [0] * n
    stack = [0]
    parent[0] = -2
    
    while stack:
        u = stack.pop()
        for v, c in graph[u]:
            if parent[v] == -1:
                parent[v] = u
                parent_cost[v] = c
                stack.append(v)
    
    ans = 0
    for u, p in reversed(order):
        if p != -1:
            ans += abs(balance[u]) * parent_cost[u]
            balance[p] += balance[u]
    
    print(ans)

if __name__ == "__main__":
    solve()
```该代码避免了递归，因为具有 250,000 个节点的树可以创建大于 Python 默认限制的递归深度。 第一次迭代遍历创建了一个后序序列，这让我们可以在处理父母之前处理孩子。 

第二次遍历记录每个节点的父节点以及将其连接到该父节点的边的成本。 这避免了在后序计算期间存储额外的状态。 

最后的循环以相反的后序遍历节点。 此时，每个子树的子树余额已经完成，因此代码可以收取边缘成本并将子树的余额合并到父树中。 

Python 整数自动处理较大的答案值。 最大成本可能约为`10^6 * 10^6 * 250000`在规模上，超过了 32 位整数限制。

 ## 边缘情况

 单一国家案例：```
1
5 3
```子树平衡为`2`，但没有父边。 遍历到达根并且不收取任何费用，产生`0`。 剩下的军队可以留在原地。 

对于包含额外和缺失军队的子树：```
3
1 2 7
2 3 4
0 2
5 1
0 3
```余额值为`-2`,`4`， 和`-3`。 遍历首先处理节点3，充电`3 * 4`对于节点 2 的边（如果它是唯一的视图）。 节点3与节点2合并后，满足内部需求后子树平衡变为零，因此只剩下必要的内部移动。 最终的答案是`4`，因为一支军队从节点 2 移动到节点 3。 

对于有剩余的根：```
1
5 3
```处理所有子项后，根平衡保持正值。 该算法有意对剩余的部队不做任何处理，因为只需部署所需的最少军队。 额外的军队可以留在任何地方。
