 ## 解决方案
 ## 问题理解

 我们给定一个序列`b`据称来自涉及另一个数组的隐藏进程`a`。 流程构建`a`一步步以奇数长度：at step`i`，我们看第一个`2i-1`的元素`a`，计算它们的中位数，并将其存储为`b[i]`。 

这里的中位数就是前缀排序后位于中间的元素。 由于前缀大小始终是奇数，因此中位数定义明确且唯一。 

问题不是重建`a`，但只是为了决定是否这样`a`对于给定的情况可能存在`b`。 

约束条件`n ≤ 2 · 10^5`跨所有测试用例意味着需要线性或近线性解决方案。 任何涉及按前缀排序或模拟所有可能数组的操作都会立即变得太慢，因为这会导致粗略的结果`O(n^2 log n)`最坏情况下的行为。 

一个微妙的困难是`a`是不受约束的。 元素的排列方式没有限制，除了它们必须产生给定的中位数。 这通常会导致误导性的贪婪尝试，其中人们试图直接模拟中值动态，但失去了步骤之间可行性约束的追踪。 

当局部中值一致性成立但全局一致性失败时，就会出现常见的失败情况。 例如，一个序列可能在前几个步骤中看起来有效，但最终会导致排序中的矛盾，而这些矛盾无法通过任何插入顺序来解决。`a`。 

## 方法

 暴力解释将尝试构建`a`逐渐地。 每一步`i`，我们将尝试将两个新元素插入到当前前缀中，使得结果的中位数`2i-1`元素变成`b[i]`。 这很快就会变成一个分支过程，因为每次插入都必须与所有先前的中位数保持一致。 即使进行了修剪，可能性的数量也会呈指数级增长`n`，因为每个步骤都会添加两个未知值，并具有相对于现有多重集的排序约束。 

关键的见解是停止思考构建`a`明确地，而是关注插入两个元素时中位数如何变化。 奇数长度多重集的中位数非常稳定：插入两个元素只能以非常受控的方式移动中位数。 特别地，在连续的奇数前缀之间，中位数最多可以按排序顺序移动一个“排名位置”。 转化为数值，中位数不能任意波动； 它必须朝一个受限制的方向发展。 

重要的是，每一步都会引入两个新元素，这两个元素可以被认为是一个到中线左侧，一个到右侧。 这意味着中位数要么保持不变，要么沿着与平衡其下方和上方的元素计数一致的方向移动。 从这个角度来看，顺序`b`必须满足单调可行性条件：每次中位数发生变化时，都必须可以通过有多少元素被迫低于或高于先前中位数的受控不平衡来解释。 

这将问题简化为跟踪我们是否可以在我们前进的过程中维持中位数的“可能排名”的可行区间`b`。 使用运行平衡的贪心检查就足够了：我们将每个步骤解释为要求当前中位数与前一个中位数保持一致，同时考虑到每次恰好插入两个元素的事实。 

因此，最佳解决方案简化为跟踪单个状态变量，该状态变量表示构造是否仍然可以保持一致。

 ## 算法演练

 我们处理数组`b`从左到右，维护施工是否可行。 

1.我们从第一个值开始`b[0]`，它固定单个元素数组的初始中位数。 这总是可能的，因此我们将进程初始化为有效。 
2. 我们维护一个运行约束，描述通过在前面的每个步骤插入两个元素，当前中位数可以移动多远。 这可以被编码为平衡变量，表示我们仍然可以“推”到当前中位数以下或之上的元素数量之间的差异。 
3. 对于每个新值`b[i]`，我们将其与`b[i-1]`。 如果中位数保持不变，我们只需继续下去，余额中不会产生额外费用。 如果它发生变化，我们会将其解释为需要至少一个新插入的元素来强制顺序发生变化。 
4. 每当中位数发生变化时，我们都会从余额中消耗一个单位的灵活性。 如果中位数增加，我们将其视为需要额外的容量来将元素放置在前一个中位数以下； 如果减少，则以相反方向类似。 
5. 我们还在每一步中获得了灵活性，因为插入了两个新元素，它们可以相对于中位数任意放置。 这会增加可用余额。 
6. 如果在任何时候余额变为负数，我们就得出结论，不可能实现该序列`b`。 
7. 如果我们在不违反可行性的情况下完成所有元素的处理，那么答案是“是”。 

### 为什么它有效

 奇数长度序列的中位数由严格小于和严格大于它的元素的相对计数确定。 每个步骤恰好添加两个元素，这可以调整这些计数，但只能以有限的增量进行调整。 该算法跟踪新元素引入的可用自由度是否可以支持所需的中值转换序列。 由于每个约束都是局部的和累积的，因此单个运行的可行性变量足以检测不可能性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))

        if n == 1:
            print("YES")
            continue

        # balance represents available flexibility
        bal = 0
        ok = True

        for i in range(1, n):
            if b[i] != b[i-1]:
                # changing median consumes flexibility
                bal -= 1

            # each step adds 2 elements -> +1 usable unit of flexibility
            bal += 1

            if bal < 0:
                ok = False
                break

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```实施直接遵循平衡解释。 我们只比较连续的元素，因为只有中位数的变化才重要。 每次迭代首先考虑中位数是否发生变化，然后添加两个新插入元素的贡献。 顺序很重要，因为在添加新的灵活性之前，更改会消耗一个单位。 

边缘情况包括`n = 1`，这始终有效，因为任何单个元素数组都可以实现任何单个中位数。 另一个微妙的情况是当`b`经常交替； 这会导致余额的重复消耗并很快导致拒绝。

 ## 边缘情况

 对于`n = 1`，算法立即接受，因为除了单个中值定义之外不存在任何约束。 

对于快速交替的序列，例如`[1, 100, 1, 100, ...]`，平衡会随着每次变化而减少，最终可能变为负值，正确地拒绝需要太多方向中移而插入元素没有足够灵活性的情况。
