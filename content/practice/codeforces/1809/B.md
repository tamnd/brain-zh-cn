 ## 解决方案
 ## 问题理解

 我们想要放置`n`平面整数格点上的芯片。 芯片的成本为`(x, y)`是它与原点的曼哈顿距离，`|x| + |y|`。 整个布置的成本是所有布置的芯片中最大的芯片成本。 

芯片必须满足一个几何限制：每对芯片必须大于`1`以欧几里得距离为单位。 

任务是找到允许精确放置的最小可能的最大成本`n`筹码。 

输入最多包含`10^4`测试用例，以及每个`n`可以大到`10^18`。 如此巨大的值立即排除了任何显式构造点或迭代到的方法`n`。 甚至一个`O(√n)`对于最大的输入，算法会太慢。 我们周围需要一些东西`O(log n)`每个测试用例。 

关键的挑战是了解在给定的成本限制内可以容纳多少个格点。 

一个微妙的边缘情况是`n = 1`。 

输入：```
1
1
```输出：```
0
```可以在原点放置一颗芯片，所以答案是`0`。 假设最小成本的解决方案至少为`1`会失败的。 

另一个重要的界限是何时`n`正好是一个完全平方数。 

输入：```
1
9
```输出：```
3
```答案不是`2`，因为成本限制为`2`仅包含`3² = 9`有效职位？ 这个观察实际上就是整个解决方案。 将计数公式弄错一会导致完美平方周围的答案不正确。 

错误的最后一个来源是处理接近的值`10^18`。 

输入：```
1
1000000000000000000
```答案是`1000000000`。 任何使用浮点平方根的实现都存在接近该范围的精度误差的风险。 整数运算更安全。 

## 方法

 蛮力思维从确定一些最大允许成本开始`k`并计算有多少个格点满足`|x| + |y| ≤ k`。 该集合在原点周围形成一个菱形。 

不考虑距离限制，该菱形中的格点数量为$$1 + 2k(k+1).$$然后可以尝试增加`k`直到存在足够的点。 

问题是距离限制改变了一切。 两个相邻的格点，例如`(0,0)`和`(1,0)`正是距离`1`分开，这是被禁止的。 我们不能使用菱形中的所有点。 

关键的观察是整数网格上的距离​​条件变得非常简单。 由于坐标是整数，因此两个不同的格点距离最多的唯一方法`1`就是它们在水平或垂直方向上是否相差一个单位。 

这表明仅选择一个奇偶校验点。 考虑所有格点，其中`x + y`是均匀的。 任何两个这样的点相差偶数`x + y`，所以它们永远不可能是水平或垂直的邻居。 他们的欧氏距离总是大于`1`。 

现在看看钻石`|x| + |y| ≤ k`。 其格点中，恰好$$(k+1)^2$$具有偶数奇偶性。 

更好的是，这是最佳的。 由水平和垂直邻接形成的格图是二分的，由奇偶性分割。 在此图中，每个可接受的集合都是一个独立的集合，并且一个奇偶校验类已经达到了最大可能的大小。 

所以在成本限制下`k`，我们可以准确地放置`(k+1)^2`筹码。 

现在问题已简化为寻找最小的`k`这样$$(k+1)^2 \ge n.$$自从`n`可以大到`10^{18}`，我们可以用二分查找来解决这个问题。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(k²) 或更差 | O(1) | O(1) | 太慢了|
 | 最佳 | O(log n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 对于候选人成本限制`k`，计算可以放置多少个芯片：$$(k+1)^2$$这是通过获取钻石内部一个宇称的所有晶格点来实现的。 
2.观察更大的`k`总是允许至少尽可能多的芯片`k`。 

功能`(k+1)^2`是单调的，这使得二分搜索适用。 
3.二分查找最小`k`这样：$$(k+1)^2 \ge n$$4. 初始化`low = 0`和`high = 10^9`。 

自从`n ≤ 10^{18}`，答案永远不会超过`10^9 - 1`。 
5. 在搜索过程中，让`mid = (low + high) // 2`。 
6. 如果`(mid + 1)^2 ≥ n`，通过设置保留左半部分`high = mid`。 

这意味着`mid`已经足够了，但可能还有更小的有效答案。 
7.否则设置`low = mid + 1`。 

这意味着`mid`无法容纳足够的芯片。 
8. 什么时候`low == high`，输出该值。 

### 为什么它有效

 对于每个成本限制`k`，内部最大有效格点集`|x| + |y| ≤ k`有尺寸`(k+1)^2`。 一个奇偶校验类达到了这个大小，并且不存在更大的独立集，因为菱形内部的晶格邻接图是二分的，较大的一侧恰好包含`(k+1)^2`顶点。 

因此成本限制`k`可行当且仅当`(k+1)^2 ≥ n`。 二分查找找到最小的可行值`k`，这正是可能的最小成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())

    lo, hi = 0, 10**9

    while lo < hi:
        mid = (lo + hi) // 2

        if (mid + 1) * (mid + 1) >= n:
            hi = mid
        else:
            lo = mid + 1

    print(lo)
```解决方案围绕单调谓词$$(k+1)^2 \ge n.$$对于任何固定的`k`，这告诉我们半径是否为菱形`k`可以包含足够的有效筹码位置。 

二分查找保持了答案始终位于内部的不变量`[lo, hi]`。 每当`mid`可行，我们继续向左搜索，因为我们想要最小的成本。 每当`mid`是不可行的，每个较小的值也是不可行的，所以我们向右移动。 

所有算术运算均使用整数执行。 这避免了在附近使用浮点平方根时可能出现的精度问题`10^18`。 

上限`10^9`就足够了，因为$$(10^9)^2 = 10^{18}.$$所以答案大于`10^9`永远不需要。

 ## 边缘情况

 考虑最小的输入：```
1
1
```搜索检查是否`(k+1)^2 ≥ 1`。 已经在`k = 0`，条件成立，因为`1² = 1`。 算法返回`0`，对应于将芯片放置在`(0,0)`。 

现在考虑一个完全平方：```
1
9
```该算法寻找最小的`k`和`(k+1)^2 ≥ 9`。 为了`k = 1`，我们得到`4`，这是不够的。 为了`k = 2`，我们得到`9`，这已经足够了。 答案是`2`。 这证实了平等必须被视为可行。 

最后，考虑：```
1
10
```为了`k = 2`，我们仍然只有`9`可用职位。 下一个值给出`(3+1)^2 = 16`， 制作`k = 3`答案。 这是典型的差一情况，捕获不正确的二分搜索条件。 

对于最大范围：```
1
1000000000000000000
```条件变为`(k+1)^2 ≥ 10^18`。 最小有效值为`k = 999999999`， 自从`(10^9)^2 = 10^18`。 整数算术可以安全地处理这个问题，避免任何浮点舍入问题。
