 ## 解决方案
 ## 问题理解

 我们被要求构造一个长度的整数数组$n$，其中每个元素必须位于一个小的有界范围内，以便非常特定的组合属性适用于其所有子数组。 

每个连续的段都贡献一个值：其元素的总和。 其中$\frac{n(n+1)}{2}$子数组，确切地说$k$其中所有子数组的和必须为正，所有剩余子数组的和必须为负。 零和子数组是隐式不允许的，因此构造必须避免产生任何总和恰好为零的子数组。 

核心困难不是计算子数组和，而是对数组进行整形，以便所有子数组和的符号模式与规定的全局计数相匹配。 

约束条件$n \le 30$非常小。 这立即排除了任何指数$n$，但更重要的是，它表明我们应该构建一个结构化模式，而不是在所有子数组上进行搜索或 DP。 取值范围$[-1000, 1000]$足够宽，我们可以使用大的正数和负数干净地分离贡献，而不必担心溢出或紧密包装。 

一个微妙的边缘情况源于每个子数组严格为正或严格为负的要求。 如果我们创建了一个总和为零的子数组，即使只有一次，该构造也会变得无效。 在不控制前缀和的情况下平衡正负的天真贪婪通常会产生零和边界。 例如，交替$1, -1, 1, -1$创建许多零和子数组，例如$[1, -1]$。 因此，真正的约束不仅仅是控制计数，而是严格区分正累积效应和负累积效应。 

另一个陷阱是假设子数组正性仅取决于单个元素。 事实并非如此。 单个大的正元素可以主导许多子阵列，而单个大的负元素可以破坏许多分段的正元素。 解决方案必须利用这种不对称性。 

## 方法

 暴力尝试会尝试分配值，然后对所有子数组进行计数，检查是否准确$k$其中有正和。 即使我们修复了候选数组，验证它的成本$O(n^2)$。 如果我们尝试搜索所有数组，甚至将值限制为$[-1000, 1000]$，搜索空间变为$(2001)^n$，完全不可行。 

即使是更结构化的蛮力，例如在逐步跟踪所有子数组总和的同时回溯每个位置，也会失败，因为每个扩展仍然会影响$O(n)$子数组，给出指数分支。 

关键的观察是我们实际上不需要独立地推理各个子数组。 相反，我们可以构造数组，以便子数组以高度受控、几乎确定的方式运行。 这种形式的问题的标准技巧是迫使每个子数组和主要取决于少量的主导元素。 

我们可以通过构建一个由两种类型的值组成的数组来做到这一点：一个大的正常量和一个大的负常量。 通过仔细选择放置多少正数和负数，我们可以控制有多少子数组“被迫”具有正和。 

使这项工作有效的结构是将每个位置视为通过前缀结构独立地对子数组的全局平衡做出贡献。 如果我们固定正元素的数量，并使它们与负元素相比足够大，那么当且仅当在受控前缀意义上子数组包含的正数多于负数时，子数组才是正数。 这使我们能够将问题简化为选择正贡献的位置，而不是推理任意总和。 

然后我们将任务简化为构造一个序列，其中$k$子阵列以正贡献为主。 因为$n$很小，我们可以贪婪地从左到右分配正数，确保每个新的正元素贡献可预测数量的新正子数组。

 | --- | --- | --- | --- |
 | 暴力搜索 | 指数| O(n^2) | O(n^2) | 太慢了|

 ## 算法演练

 构建依赖于目标的分裂$k$转化为与选择某些子阵列变为正值相对应的贡献。 我们使用精心选择的大常数来强制控制，以便符号行为稳定。 

1. 从空数组和完整目标开始$k$，代表我们还需要实现多少个正和子数组。 
2. 从左到右迭代位置。 在每个位置$i$，根据它可以引入多少个新的正子数组来决定是否放置正值或负值。 

关键思想是在位置上设置正值$i$准确地创造$i$子数组结束于$i$，如果该值主导其余值，则所有这些子数组都变为正数。 
3. 如果剩余的$k$至少是$i$，在位置处放置一个大的正数$i$并减去$i$从$k$。 这贪婪地解释了所有以$i$从任何较早的索引开始。 

这样做的原因是每个这样的放置都会“激活”所有以$i$为正，我们通过严格区分震级来确保以后不会取消。 
4. 如果$k < i$，改为放置一个大负数。 这确保了涉及该位置的子数组不会意外地变为正值，从而保留了仅显式计算的子数组对计数有贡献的不变量。 
5. 处理完所有位置后，用足够大的负值调整剩余的无约束位置，以便不会出现意外的正子数组。 

### 为什么它有效

 不变的是处理后的位置$i$，以或早于结尾的子数组中正和子数组的数量$i$正是我们从中减去的金额$k$。 每个积极的位置都有准确的贡献$i$新的正子数组，因为它支配所有以$i$，负数放置贡献零个新的正子数组，因为它们抑制了涉及它们的任何候选正和。 由于选择幅度是为了防止跨段抵消，因此子数组符号仅取决于它们是否包含指定的正“锚”位置，从而使计数准确且不重叠。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        
        a = []
        # we construct using a greedy decomposition of k into triangular contributions
        # position i contributes at most i new positive subarrays
        
        for i in range(1, n + 1):
            if k >= i:
                a.append(1000)   # strong positive anchor
                k -= i
            else:
                a.append(-1000)  # strong negative blocker
        
        print(*a)

if __name__ == "__main__":
    solve()
```该代码实现了从左到右的贪婪赋值。 在每个索引处$i$，我们决定是否“花费”$i$剩余配额单位$k$。 选择正值意味着该位置成为一个锚点，保证所有子数组都以$i$是积极的，贡献确切$i$有效的子数组。 如果我们无法承担这一贡献，我们会放置一个较大的负值，以确保不会创建新的正子数组。 

的选择$1000$和$-1000$是经过深思熟虑的，因为它保证了幅度的强烈分离，防止混合子数组意外取消预期的符号行为。 

一个微妙的一点是我们永远不会重新审视之前的决定。 这是安全的，因为每个位置的贡献是独立的并且在子阵列端点方面是可加的。

痕迹表明，一旦我们承诺一个积极的锚，它的贡献是固定的，不会干扰以后的决策。

 ## 边缘情况

 一个关键的边缘情况是$k = 0$，其中每个子数组都必须为负数。 该算法立即拒绝所有正位置并用以下内容填充数组$-1000$。 每个子数组的总和都变为负数，因为每个元素都严格为负数。 

另一个边缘情况是$k = \frac{n(n+1)}{2}$，其中所有子数组都必须为正。 在这种情况下，每个位置都满足$k \ge i$，因此该算法将数组完全填充为$1000$。 每个子数组的和都是正数，因为它是严格正数的和。 

一个微妙的中间情况发生时$k$不是三角形的。 贪婪仍然有效，因为它会分解$k$分解为不同整数的和$i$，并且每当无法使用某个值时，就会跳过该值，而不会破坏之前的承诺。 这确保了部分贡献不会干扰，因为每个位置根据其索引独立贡献。
