 ## 解决方案
 ## 问题理解

 我们得到了参与者评级的排序列表，并且我们可以将这些参与者排列成一行。 确定排列后，将进行连续的锦标赛：前两名选手进行战斗，然后获胜者立即与队伍中的第三名选手进行战斗，然后该比赛的获胜者与第四名选手进行战斗，依此类推，直到最后一名参赛者。 

当评分差距很大时，每场比赛都会表现出确定性：如果两个玩家之间的绝对差异超过阈值$k$，评分较高的玩家总是获胜。 当差异最大时$k$，结果是任意的，可能会发生任何一种情况。 

关键要求是，选择排列后，Monocarp 必须能够提前预测每场比赛的结果，这意味着对于序列中的每场比赛，获胜者都是由评分和上述规则唯一确定的，不会出现“小间隙”对带来的歧义。 

我们需要计算有多少参与者的排列使这个属性成立。 

约束条件非常大，$n$最多一百万。 这立即排除了任何试图模拟所有排列甚至任何二次结构的解决方案。 评级已经排序，这是一个强有力的结构提示：答案必须仅取决于我们如何放置索引，而不是反复比较任意对。 

当我们假设局部有效性意味着全局有效性时，就会出现微妙的失败案例。 例如，假设三个评级是$1, 10, 20$和$k = 5$。 这对$10, 20$是确定性的，但是$1, 10$不是。 一个天真的想法可能是“只要每个相邻对都是确定性的，整个链就很好”，但这是错误的，因为早期比赛的获胜者会改变未来参与者的身份。 

另一个常见的陷阱是将过程视为仅取决于排列中的相邻差异。 实际上，获胜者会传播，因此约束是全局的，并且取决于不确定性如何在锦标赛中传播。 

## 方法

 暴力方法会尝试每一种排列，模拟锦标赛，并检查每场比赛的结果是否是唯一确定的。 即使我们乐观地模拟一场锦标赛$O(n)$，总复杂度变为$O(n! \cdot n)$，即使对于$n = 20$。 瓶颈不是模拟本身，而是排列的组合爆炸。 

关键的观察是，只有当获胜者链跨越“危险边界”时，才会出现不确定性，这意味着一对的评级差异最多为$k$。 当两个玩家的评级相差很大时，实力较强的玩家总是占据主导地位，并有效地阻止任何歧义的传播。 

因为评级是排序的，所以我们可以将问题重新解释为控制如何交错小值和大值，以便歧义永远不会以分支结果的方式传播。 该过程的结构意味着，在每一步中，当前的获胜者必须是连续“活动窗口”值中的最大值（或最小值，取决于视角），这些值仍然足够接近以进行潜在的交互。 

这导致了贪婪的组合结构：我们从起点扩展一个有效段，维护一个范围不超过的值窗口$k$，并计算我们可以选择插入顺序同时保留单个确定性结果链的方式有多少种。 每个有效的构造都对应于选择一个永远不会在窗口中引入分裂的排序，其中两个未解决的候选者都可以在匹配中幸存。 

最终计数减少为乘以每个“有效块扩展”的贡献，其中在每个阶段，我们决定是否通过从当前可行区间的左侧或右侧获取新元素来扩展活动段，但前提是评级约束保持在$k$。 

这将全局排列计数转换为排序位置上的受控计数过程，可以在线性时间内处理。

 ## 算法演练

 我们将排序后的数组解释为一条线，其中我们维护一个可行的值段，其范围保持在由下式控制的窗口内$k$。 构建过程是通过扩展该部分来进行的，同时确保任何步骤都不会给锦标赛结果带来歧义。 

1. 从单个元素开始作为初始活动段。 这表示修复序列中的第一个参与者。 
2.维护两个描述当前段的指针$[l, r]$，最初都在某个起始索引处。 
3. 尝试向左或向右扩展分段，但前提是添加该元素可以使分段保持“安全”，这意味着它不会造成活动区域内的两个元素可能产生相对于当前获胜者链不明确的匹配结果的情况。 
4. 在每个扩展步骤中，计算存在多少个用于扩展段的有效选择。 每个有效选择对应于以保留获胜者确定性传播的方式选择排列中的下一个参与者。 
5. 乘以所有步骤中有效扩展的数量，因为一旦当前活动段固定，不同扩展阶段的选择是独立的。 
6. 继续，直到所有元素都包含在段中。 

关键的计算任务是跟踪每侧有多少元素保持在距离内$k$当前边界。 由于数组已排序，因此可以使用两个指针在每个元素的摊销常数时间内更新这些计数。 

### 为什么它有效

 该过程强制在每一步中当前未解决的区域仍然是值空间中的单个连接区间，其中所有潜在的相互作用仍然由$k$- 阈值规则。 任何违反这一点的排列都必然会引入一种情况，即两个未解决的候选者都可以在与当前链的匹配中生存下来，从而使得 Monocarp 无法唯一地确定结果。 相反，仅通过扩展有效边界构建的任何排列可确保获胜者链在每一步都是确定性的，因此每个比赛结果都是固定的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    # Two pointers defining a valid expanding window
    l = 0
    ans = 1

    for r in range(n):
        # ensure window is valid in value range
        while a[r] - a[l] > k:
            l += 1

        # number of choices to place current element
        ans = (ans * (r - l + 1)) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```该代码在排序的评级上维护一个滑动窗口。 对于每个位置$r$，它会发现我们可以走多远，同时将差异保持在$k$。 这定义了当前有多少元素可以在不破坏确定性的情况下进行排列。 因素$(r - l + 1)$计算当前元素在演化结构中的有效位置，并将这些选择相乘得出有效排列的总数。 

关键的微妙之处在于，排序确保一旦左边界向前移动，它就永远不需要向后移动。 这保证了摊销线性复杂度。

 ## 边缘情况

 当所有值都相同并且$k = 0$，每场比赛都是模棱两可的。 窗口永远不会缩小，所以一步一步$r$， 全部$r+1$元素是有效的选择，产生$n!$。 滑动窗正确保持$l = 0$，因此产品变为$1 \cdot 2 \cdot \dots \cdot n$。 

当值严格增加但$k$较小时，左指针频繁前进。 用于输入$1,2,3,4$和$k=1$，窗口大小在 1 和 2 之间振荡，乘积反映了受限的局部选择。 该算法捕获了这一点，因为每次违规都会立即转移$l$，防止过度计数。 

当存在较大间隙时，例如$1, 100, 1000$，窗口在多个点折叠为单个元素。 在这些步骤中，乘积大部分乘以 1，反映了强制结构。
