 ## 解决方案
 ## 问题理解

 我们有两个具有固定容量的容器。 第一个可以坚持`a`水单位和第二个最多`b`。 我们还收到一个初始配置，其中第一个坦克以`c`单位和第二个`d`，这个初始对可以是整个矩形中的任意点`[0, a] × [0, b]`。 

然后应用一系列操作。 每个操作都描述了在两个水箱之间移动水的尝试。 如果操作值为正，我们尝试将水从第一个水箱转移到第二个水箱中。 如果是负值，我们就尝试向相反的方向输送水。 每次转移同时受到三个因素的限制：我们想要移动多少，源水箱中有多少可用水，以及目的地水箱中剩余多少可用容量。 

最终任务不是模拟一个初始状态，而是计算每个可能的起始对在第一个罐中的最终数量`(c, d)`。 这将问题转化为评估大小约为一百万个状态的网格的变换，因为`a, b ≤ 1000`。 

一种天真的解释建议独立模拟每个起始状态，应用所有`n ≤ 10^4`运营。 这已经花费了大约`10^4 × 10^6 = 10^10`更新，这远远超出了可行的范围。 

一个不太明显的困难是该过程在代数意义上不是线性的。 每个操作都会根据可用性和剩余容量进行剪辑，因此中间状态的微小变化可以以非线性方式传播。 尝试仅跟踪总数或平均值的简单 DP 会失败，因为系统依赖于精确的整数边界。 

打破简单推理的关键边缘情况是饱和。 例如，如果一个储罐已满，则未来转移到该储罐的行为与部分空储罐时的行为有所不同，即使差异只有一个单位。 这意味着任何状态压缩都必须保留精确的分段行为。 

## 方法

 蛮力方法会迭代所有`(c, d)`配对并模拟每个的整个序列。 每个模拟都是`O(n)`，因此总复杂度变为`O(a · b · n)`，在最坏的情况下大约是`10^10`运营。 这是不可行的。 

关键的观察结果是系统是分段线性且单调的，但断点完全由容量控制`a`和`b`，而不是操作次数。 每次操作之后，状态网格的转换仍然是一个网格，其中值仅沿着容器变满或变空的边界变化。 由于容量很小（≤ 1000），我们可以显式地维护完整的状态空间并逐步更新它。 

我们维护一个 2D DP 表，而不是从头开始重新计算每个初始状态`dp[x][y]`表示处理某些操作前缀后第一个罐中的数量，从初始开始`(x, y)`。 每个操作都会将整个表转换为`O(a·b)`通过计算相邻州之间局部推水的效果来计算时间。 由于每个步骤仅取决于当前单元格，因此我们不需要重新计算历史记录。 

因此，问题简化为应用一系列`n`有界网格上的全局变换，每个变换都在网格大小上以线性时间进行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(a·b·n) | O(a·b·n) | O(1) 额外 | 太慢了|
 | 网格DP仿真| O(n·a·b) | O(n·a·b) | O(a · b) | O(a · b) | 已接受 |

 ## 算法演练

 我们维护一个网格`dp[x][y]`， 在哪里`x`是罐 1 中的当前数量，`y`是罐 2 中的当前数量。最初，该网格的身份是：每个州`(c, d)`映射到最终`(c, d)`在进行任何操作之前。 

每一次操作都会将该网格转变为一个新网格。 

1. 初始化`dp[x][y] = x`为所有人`0 ≤ x ≤ a`,`0 ≤ y ≤ b`。 这编码了这样一个事实：在任何操作之前，第一个储罐恰好包含`x`。 
2.对于每个运算值`v`,构造一个新的网格`ndp`。 
3.如果`v > 0`，我们模拟将水从水箱 1 推到水箱 2。对于每个状态`(x, y)`，转移金额的界限为`x`和`b - y`。 结果状态变为`(x - t, y + t)`在哪里`t = min(v, x, b - y)`。 网络分配`ndp[x][y] = dp[x - t][y + t]`，因为移动之后，我们到达一个新的状态，其最终值已经从之前的 DP 层中得知。 
4. 如果`v < 0`，我们进行对称操作：水从水箱 2 移动到水箱 1。对于每个`(x, y)`, 计算`t = min(-v, y, a - x)`，并过渡到`(x + t, y - t)`。 我们设定`ndp[x][y] = dp[x + t][y - t]`。 
5. 更换`dp`和`ndp`并继续。 

处理完所有操作后，`dp[c][d]`直接给出该起始配置的罐 1 中的最终数量。 

关键思想是，我们不是在每个状态的时间上向前发展水量，而是通过每个操作引起的转换向后推动整个映射。 

### 为什么它有效

 每个操作都定义了从最终状态回到先前状态的确定性映射。 因为在给定操作下每个状态都恰好有一个前驱（因为移动量由容量约束唯一确定），所以变换在可行网格上是双射的。 这确保了通过反向转换传播值可以保持正确性，而不会发生冲突或歧义。 DP 表本质上是跟踪所有操作中这些双射的组成。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    v = list(map(int, input().split()))

    dp = [[i for j in range(b + 1)] for i in range(a + 1)]

    for move in v:
        ndp = [[0] * (b + 1) for _ in range(a + 1)]

        if move > 0:
            for x in range(a + 1):
                for y in range(b + 1):
                    t = min(move, x, b - y)
                    nx, ny = x - t, y + t
                    ndp[x][y] = dp[nx][ny]
        else:
            mv = -move
            for x in range(a + 1):
                for y in range(b + 1):
                    t = min(mv, y, a - x)
                    nx, ny = x + t, y - t
                    ndp[x][y] = dp[nx][ny]

        dp = ndp

    out = []
    for x in range(a + 1):
        out.append(" ".join(str(dp[x][y]) for y in range(b + 1)))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码初始化一个完整的状态表，并在每次操作后重复重写它。 嵌套循环反映了每个状态转换仅依赖于本地容量约束的事实，因此每次更新都可以直接计算，无需递归或额外的结构。 最终表格逐行打印，符合所需的输出格式。 

边界处理隐含在`min`确保转移的水量不会超过可用水量或剩余容量。

```我们跟踪单个状态`(c=3, d=2)`。

 ## 边缘情况

 当一个储罐在传输开始时已满或已空时，就会出现一种关键的边缘情况。 例如，如果`a = b = 2`,`c = 2`,`d = 0`，并且我们尝试从水箱 1 移动到水箱 2，没有水移动，因为根据方向，目的地已满或水源为空。 该算法可以正确处理这个问题，因为`t = min(x, b - y, v)`自动变为零，保持状态不变。 

另一种情况是重复饱和和释放，其中水在水箱之间振荡而没有完全转移预期的量。 DP 转换始终遵循瞬时容量约束，因此即使重复操作也能保持一致，因为每个步骤都会根据当前的精确状态而不是任何近似值重新计算可行性。
