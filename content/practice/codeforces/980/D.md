 ## 解决方案

 ## 问题理解

 我们得到一个整数数组，对于该数组的每个连续段，我们想象一个单独的分区任务。 在选定的段内，我们必须将其元素分成尽可能少的组，以便在每个组中，任何两个数字的乘积都是完全平方数。 

分组条件在每个组内是全局的：相邻元素表现良好是不够的，组内的每一对都必须满足完全平方乘积条件。 对于每个子数组，我们计算此类组的最小数量，最后我们计算有多少个子数组产生每个可能的答案值。 

解释该条件的直接方法是用素数指数来思考。 当每个素数的总指数为偶数时，乘积就是完全平方数。 这意味着在删除所有平方因子后，每个数字的结构对于组内的兼容性至关重要。 

约束允许最多 5000 个元素。 子数组的二次方数量已经达到约 1250 万个段，因此任何大致为 O(n²) 的解决方案都处于可行性边界上，而任何三次或涉及每个子数组的大量因式分解的解决方案都将太慢，除非进行大量优化。 这立即将我们推向一种解决方案，其中每个子数组都通过小​​量摊销更新进行增量处理。 

当所有数字都是相同的平方时，例如所有元素都是 1 或 4 或 9，就会出现微妙的边缘情况。在这种情况下，每个元素都彼此兼容，因此每个子数组都有答案 1。错误地将相同值视为不兼容的简单方法会错误地对组进行计数。 当数字不同但共享相同的无平方核心时，会出现另一种边缘情况，例如 2 和 8，在去除平方因子后都减少到 2； 这些仍然必须组合在一起。 

## 方法

 蛮力策略将独立检查每个子数组。 对于每个子数组，我们将尝试构造组，在具有不同无平方结构的元素不能共存于同一组的约束下有效地模拟分区。 一个简单的解释是，每个不同的“无平方类型”都会强制其自己的组，因此子数组的答案是其中不同的标准化值的数量。 

然而，从头开始为每个子数组重新计算这些不同的值会导致 O(n3) 过程：有 O(n2) 个子数组，在最坏的情况下，子数组的每次扫描成本为 O(n)。 对于 n 达到 5000 的情况来说，这太慢了。 

关键的观察结果是分组条件分解为简单的分类问题。 每个整数都可以简化为无平方核，即在因式分解中以奇数指数出现的素数的乘积。 当且仅当它们的无平方核相同时，两个数字才能共存于同一组中，因为只有相同的奇偶校验模式才能保证它们的乘积是完美的平方。 这将每个子数组内的问题转化为一个简单的问题：出现了多少个不同的无平方核。 

一旦理解了这一点，任务就变成了对所有子数组上的不同元素进行计数，这可以通过固定左端点并扩展右端点同时维护频率表来完成。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个子数组的强力分组 | O(n3) | O(n) | 太慢了|
 | 具有无平方标准化的滑动窗口 | O(n²) | O(n) | 已接受 |

 ## 算法演练

 ### 1. 将每个数字归一化为其无平方核

我们通过对每个值进行因式分解并仅保留出现奇数次的素数来对其进行预处理。 这会产生一个规范表示，其中具有相同分组行为的所有数字变得相等。 

此步骤是必要的，因为分组条件仅取决于指数奇偶性，而不取决于实际大小。 

### 2. 修复子数组的左端点

 我们迭代子数组的所有可能的起始索引。 对于每个起点，我们逐渐延伸右端点。 

### 3. 维护频率图，同时扩展右端点

 当我们扩展子数组时，我们跟踪每个无平方核出现的次数。 我们还维护一个计数器，用于记录当前存在多少个不同的内核。 

这允许我们在每次扩展后在 O(1) 时间内更新每个子数组的答案。 

### 4. 对于每个扩展，记录不同内核的数量

 当我们扩展到新的右端点时，当前不同内核的数量正是该子数组的答案。 

我们增加该值的全局答案桶。 

### 5. 汇总所有起点的结果

 处理完所有左端点后，我们获得所有可能答案的计数。 

### 为什么它有效

 在任何子数组内，有效分组强制每个组仅包含具有相同无平方核的数字。 由于两个不同的内核不能共存于一个组中，因此每个不同的内核都需要自己的组。 相反，所有相等的核都可以放在一组中，因为它们的成对乘积是完美的平方。 这使得组的最小数量恰好等于不同归一化值的数量，并且滑动窗口正确地枚举所有子数组的这些计数，而无需重新计算。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_spf(limit):
    spf = list(range(limit + 1))
    for i in range(2, int(limit ** 0.5) + 1):
        if spf[i] == i:
            step = i
            start = i * i
            for j in range(start, limit + 1, step):
                if spf[j] == j:
                    spf[j] = i
    return spf

def square_free(x, primes):
    x = abs(x)
    if x == 0:
        return 0
    res = 1
    for p in primes:
        if p * p > x:
            break
        cnt = 0
        while x % p == 0:
            x //= p
            cnt ^= 1
        if cnt:
            res *= p
    if x > 1:
        res *= x
    return res

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    limit = 10000
    spf = build_spf(limit)
    primes = [i for i in range(2, limit + 1) if spf[i] == i]

    norm = [square_free(x, primes) for x in a]

    ans = [0] * (n + 1)

    for l in range(n):
        freq = {}
        distinct = 0
        for r in range(l, n):
            v = norm[r]
            if v not in freq:
                freq[v] = 0
            if freq[v] == 0:
                distinct += 1
            freq[v] += 1

            ans[distinct] += 1

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```该代码首先将每个整数压缩到其无平方内核中。 这是唯一使用数论的部分，它确保在任何子数组处理开始之前解决所有结构等价性。 

然后，嵌套循环会枚举 O(n²) 中的所有子数组。 对于每个左端点，字典`freq`跟踪每个标准化值在当前后缀中出现的次数。 变量`distinct`增量维护，仅当新内核首次出现在该子数组中时才增加。 

数组`ans`累积按不同内核计数分组的子数组的计数，这直接对应于所需的最小组数。 

标准化时需要小心：使用绝对值可以避免负数问题，因为符号不会影响完美平方条件。 因式分解循环停止于`p * p > x`，以及任何剩余的`x > 1`已经是一个主要因素并且有直接贡献。

 ## 边缘情况

 所有元素都是完全平方的情况展示了系统最压缩的行为。 用于输入`[9, 16, 25]`，每个数字都减少到`1`经过无平方归一化后，因此每个子数组恰好有一个组。 该算法可以处理此问题，因为所有条目都映射到相同的键，并且不同的计数器永远不会增加到超过 1。 

一个对比的情况是每个元素都有一个独特的无平方核，例如`[2, 3, 5, 7]`。 子数组的每次扩展都会将不同计数加一，直到等于子数组长度。 频率图确保每个新内核在第一次出现时就被精确计数一次，并且永远不会再次出现。 

当数字不同但归一化为相同内核时，会出现更微妙的情况，例如`2, 8, 18`。 即使原始值差异很大，标准化步骤也会将它们压缩为单个代表。 该算法正确地将整个范围视为一组，因为频率结构只看到一个键。
