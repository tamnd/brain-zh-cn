 ## 解决方案

 ## 问题理解

 我们得到一个像素强度序列，每个像素强度都是 0 到 255 之间的整数。任务是通过首先划分整个值范围来“简化”该序列$[0, 255]$分成连续的段。 每个段的长度最多$k$，并且该范围内的每个整数都必须恰好属于一个段。 对于每个段，我们选择一个代表值，称为其键。 之后，每个像素值都被它所属的段的键替换。 

最终的输出是变换后的像素阵列。 在划分范围和选择键的所有有效方法中，我们需要字典顺序最小的结果数组。 

重要的交互是变换仅取决于值的分段，而不取决于数组中的位置。 一旦我们决定哪个值映射到哪个键，所有出现的该值都会被一致地替换。 

值域上的约束很小（只有 256 种可能的颜色），但数组长度上的约束很大$n \le 10^5$。 这立即表明任何解决方案都应该预先计算所有 256 个值的映射，然后在线性时间内将其应​​用于数组。 

一个天真的方法会尝试所有的分割$[0,255]$。 由于每个段的长度最多$k$，这成为一个具有指数选择的组合划分问题。 尽管 256 很小，但在所有可能的段边界上进行分支仍然会导致可能性的爆炸。 

第二个天真的想法是贪婪地选择一个分区来最小化转换后的数组，而不考虑全局交互。 这就是发生微妙故障的地方：有关段边界的早期决策会影响未来的键，而局部最优选择可以增加以后的词典价值。 

典型的失败场景来自于选择的段键不是其块中的最小值。 例如，如果我们分组$[2,3,4]$带钥匙$3$，但我们可以选择关键$2$，那么每次出现 2 时，按字典顺序都会变差。 即使后面的片段改善了其他位置，字典顺序也是由第一个不同的索引决定的。 

因此，关键的难点是：必须协调段边界和所选键，以优化全局字典顺序。 

## 方法

 暴力方法将枚举每个有效分区$[0,255]$最多分成长度的段$k$。 对于每个分区，我们将尝试每个段内键的所有可能选择，并计算所有 256 个值的结果映射，然后将其应用于数组并按字典顺序比较结果。 即使我们只考虑分段，以最大块大小切割 256 长度数组的方法数$k$256 呈指数增长，这使得这是不可行的。 

关键的观察结果是值域是固定的且很小，因此我们不应该考虑数组中的位置，而应该考虑映射每个值$v \in [0,255]$至其最终代表。 一旦这个映射被固定，构建输出就很简单了。 

现在考虑最终数组的字典顺序如何表现。 数组中最早的不同位置完全取决于获得不同映射结果的最小像素值。 这表明应尽早并尽可能有利地处理较小的值。 

在任何段内，与在同一段内选择较小的键相比，选择较大的键只会使值更差或相等。 因此，对于固定段，最佳选择始终是其最小值。 

这将问题简化为仅选择段边界。 各段$[l, r]$（和$r - l + 1 \le k$) 将其中的每个值映射到$\min(l, r)$是不正确的； 相反，它映射到$\min$从概念上讲，该段中存在的值的数量，但由于所有整数都存在于该范围内，因此最佳代表就是$l$。 因此，每个段都成为一个块，其中所有值都映射到其左端点。 

现在我们必须选择在哪里削减范围。 贪心策略是总是从 0 开始取最大可能的段，最早提高字典顺序。 但关键的简化更加强大：我们可以按升序决定每个值的映射，始终确保我们将段尽可能扩展至大小$k$，因为延迟切割只会迫使较大的值更早地共享较小的代表，这在字典顺序上始终是最佳的。 

这导致了一个简单的贪婪：我们遍历值 0 到 255，将每个值分配给当前段，并且每当该段达到大小时$k$，我们开始一个新的。 每个段的键是它的第一个值。 

这会生成所有 256 个值的固定映射，然后我们将其应用到数组。

 | --- | --- | --- | --- |
 | 暴力分区| 指数| O(1) | O(1) | 太慢了|
 | 贪婪固定大小分割| O(256 + n) | O(256 + n) | 奥(256) | 已接受 |

 ## 算法演练

 我们从每个值构建一个映射$0 \ldots 255$到其最终压缩值。 

1.初始化一个空的映射数组`mp`大小为 256。设置一个变量`start = 0`，它标记当前段的开始。 
2. 迭代值`v`从 0 到 255。 
3. 分配`mp[v] = start`，表示当前段中的所有值都映射到段开头。 
4.如果我们已经分配了$k$自上一段开始以来的值，我们移动`start = v + 1`，开始一个新的段。 

这确保每个段的大小最多$k$，并且我们总是选择最早的代表。 
5. 处理完所有值后，我们对每个可能的像素强度都有完整的映射。 
6. 通过替换每个值来转换输入数组`p[i]`和`mp[p[i]]`。 

这样做的原因是，一旦将值分配给从`start`，为它分配任何更大的代表只会增加最终数组中它出现的所有位置的值。 由于字典顺序是从左到右决定的，因此使任何早期值变大都无法在以后得到补偿。 贪婪分段确保我们永远不会以可能增加早期映射值的方式延迟边界。 

不变的是，对于每个已处理的值前缀，映射对于仅包含这些值的所有数组来说已经是最佳的，因为每个段始终使用尽可能小的代表并且永远不会超过大小$k$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))
    
    mp = [0] * 256
    
    start = 0
    cnt = 0
    
    for v in range(256):
        mp[v] = start
        cnt += 1
        if cnt == k:
            start = v + 1
            cnt = 0
    
    res = [str(mp[x]) for x in arr]
    print(" ".join(res))

if __name__ == "__main__":
    solve()
```该代码首先在 256 个可能的像素值的固定域上构建映射。 变量`start`跟踪当前段的左边界。 每次我们分配`k`值到一个段，我们重置`start`开始一个新的块。 

变换步骤是直接的：每个像素在恒定时间内被其预先计算的映射值替换。 

一个微妙的点是我们永远不需要显式存储段范围。 这对`(start, cnt)`隐式定义当前段。 此外，我们不需要担心完整段会在 255 处完全结束，因为部分段是允许的并会自动处理。

 ## 边缘情况

 一个关键的边缘情况是当$k = 1$。 该算法强制每个值立即开始一个新段，因此`mp[v] = v`。 这会产生恒等映射，这是正确的，因为没有两个不同的值可以共享一个组。 

另一种情况是$k = 256$，其中整个范围变成单个段。 这里所有值都映射到 0，因为该段从 0 开始并且永远不会重置。 该算法正确地生成了完全展平的数组。 

更微妙的情况是，当输入中的值稀疏时，例如只有像 200 到 210 这样的大值。映射仍然是在 0 到 255 的整个范围内全局确定的，因此这些值可能会落入与预期不同的段中。 该算法仍然有效，因为分段是独立于输入分布而固定的，这是问题定义所要求的。
