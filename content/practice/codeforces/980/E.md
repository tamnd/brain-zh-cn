 ## 解决方案
 ## 问题理解

 我们有一棵树$n$节点。 每个节点代表一个地区，道路系统保证任意两个地区之间只有一条简单路径。 各区$i$贡献的值等于$2^i$，因此编号较高的地区比编号较低的地区更有价值。 

我们必须准确地删除$k$地区。 移除后，剩余的区域仍必须在原始道路下形成连通图，这意味着您仍然可以在任意两个剩余节点之间行驶，而无需经过移除的节点。 在所有有效的删除方法中$k$节点，我们想要最大化$2^i$在剩余节点上，这相当于最小化删除高索引节点的影响。 

指数权重很重要，因为$2^i$主导较小指数的任何组合。 这意味着目标本质上是字典顺序的：保留较高编号的节点始终比任何较低编号的节点的集合更重要。 

约束条件允许$n$最多$10^6$，因此任何解必须接近线性或$O(n \log n)$。 二次策略（例如重复重新计算连接性或通过完整图检查模拟删除）速度太慢。 

一个微妙的点是并非每个节点子集都是允许的。 即使一组节点的总权重很高，如果它断开了剩余图的连接，也是无效的。 例如，提前移除中央关节节点可能会将剩余节点分裂成多个组件，这是被禁止的。 

另一个边缘情况是当树是一颗星时。 如果节点 1 是中心，而我们过早将其删除，则所有剩余节点都会变得孤立。 例如，如果$n = 4$和边缘是$1$连接到$2,3,4$，删除节点 1 首先留下三个孤立的节点，这违反了连通性。 因此，删除必须尊重结构约束，而不仅仅是值排序。 

## 方法

 暴力方法会尝试大小的所有子集$n-k$，检查导出子图是否连通，并计算权重之和。 即使忽略连通性检查，子集的数量也是$\binom{n}{k}$，即使对于小规模来说也是不可行的$n$。 每个候选者进行一次连接检查已经花费了成本$O(n)$，使得这种方法呈指数级增长且无法使用。 

关键的观察来自于理解树中删除时如何保留连接性。 在树中，仅当该节点是当前剩余集的连接点时，删除该节点才能断开剩余图的连接。 然而，在树中，每个节点都成为潜在的连接点，除非它是当前剩余图的叶子。 

这导致了结构的简化：如果我们希望剩余的图在整个删除过程中保持连接，我们只能删除当前剩余树中作为叶子的节点。 删除任何内部节点都会将剩余的顶点分成至少两个组件。 

一旦我们接受这个限制，问题就变成了一个贪婪的过程。 我们反复摘下一片叶子。 由于我们希望最大化剩余总和，并且较高的索引更有价值，因此我们应该更喜欢在每一步中删除最小的可用叶子。 首先删除较小的标签可以尽可能长时间地保留较大的标签，同时保持连接性。 

可以使用当前叶的优先级队列来动态维护该进程。 每次我们删除一个叶子时，它的邻居可能会成为一个新叶子，我们会进行相应的更新。

 | 蛮力 | 指数| O(n) | 太慢了|
 | 剪叶贪堆|$O(n \log n)$| O(n) | 已接受 |

 ## 算法演练

 我们维护剩余树中节点的当前度数以及始终为我们提供最小编号的可移动叶子的结构。 

1. 计算邻接表中每个节点的度。 这表示每个节点当前有多少个活动连接。 
2. 初始化一个最小堆，其中包含度数恰好为 1 的所有节点。这些是当前叶子节点，只有这些节点可以安全删除而不会破坏连接。 
3. 准确重复以下过程$k$次。 每次重复对应于删除一个节点。 
4. 从堆中提取最小索引节点。 这确保我们删除当前所有安全选择中最不有价值的节点，这与最小化指数权重的损失相一致。 
5. 将此节点标记为已删除。 这意味着它不会出现在最终的连接组件中。 
6. 对于该节点的唯一邻居，将其度数减一，因为到删除节点的边消失了。 如果这个邻居的度数变成 1 并且它还没有被删除，它就会成为一个新的叶子并被插入到堆中。 
7. 继续直到$k$节点已被删除。 

经过这些步骤后，剩下的节点就形成了一个连通子树，而被移除的节点正是该过程中记录的节点。 

正确性取决于剩余图始终连接的不变性，并且每次删除都会保留此属性，因为我们只删除叶子。 此外，在所有有效的叶子移除序列中，始终选择最小的标签叶子可确保在结构上尽可能长的时间内保留较高的标签，由于指数加权，这是最佳的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

n, k = map(int, input().split())
adj = [[] for _ in range(n + 1)]
deg = [0] * (n + 1)

for _ in range(n - 1):
    a, b = map(int, input().split())
    adj[a].append(b)
    adj[b].append(a)
    deg[a] += 1
    deg[b] += 1

removed = [False] * (n + 1)
heap = []

for i in range(1, n + 1):
    if deg[i] == 1:
        heapq.heappush(heap, i)

ans = []

for _ in range(k):
    while heap:
        v = heapq.heappop(heap)
        if not removed[v]:
            break

    removed[v] = True
    ans.append(v)

    for to in adj[v]:
        if not removed[to]:
            deg[to] -= 1
            if deg[to] == 1:
                heapq.heappush(heap, to)

ans.sort()
print(*ans)
```邻接列表有效地存储树，度数组跟踪当节点被删除时每个节点仍然具有多少个活动边。 堆确保我们总是选择最小的有效叶子$O(\log n)$时间。 

一个微妙的实现细节是堆中的延迟删除。 节点在不再是有效叶子后可能仍保留在堆中，因此我们在弹出时跳过已删除的节点。 这避免了昂贵的堆维护。 

对最终答案进行排序是必要的，因为移除是按流程顺序生成的，而不一定是升序。

 考虑示例输入：```
6 3
2 1
2 6
4 2

```最初，叶子是度数为 1 的节点：节点 1、3、4、5。堆始终选择最小的叶子。 

| 步骤| 堆（概念）| 选择| 已删除 | 度数变化 |
 | --- | --- | --- | --- | --- |
 | 1 | 1,3,4,5 | 1 | {1} | 节点 2 度减小 |
 | 2 | 3,4,5 | 3 | {1,3} | 节点 2 度减小 |

 处理后，移除的节点为$1, 3, 4$，匹配预期输出。 

该痕迹表明，该算法始终删除安全边界节点，并且从不触及内部结构，直到它自然成为叶子。 

作为第二个例子，考虑一条链：```
5 2
1 2
2 3
3 4
4 5
```叶子从 1 和 5 开始。该算法首先删除 1，然后删除 5。剩余的图保持连接，因为删除路径的端点会保留较短的路径。 

| 步骤| 叶子| 选择| 已删除 |

 ## 边缘情况

 在星形树中，一开始只有叶子是可移动的。 该算法正确地将删除限制在叶节点，因此中心永远不会过早删除。 例如，有边缘$1$连接到$2,3,4$，初始堆包含$2,3,4$，并且节点 1 在成为叶子之前永远不会进入堆，除非所有其他节点都被删除，否则这种情况永远不会发生。 

在一条长链中，只有当端点被移除后，内部节点才会逐渐变成叶子。 该算法自然会尊重这种转换，因为度更新确保节点仅在结构有效时才进入堆。 

在存在多个叶子的情况下，始终选择最小的索引可确保首先确定性地删除较低值的节点，这与指数权重一致，并防止低索引节点的次优保留。
