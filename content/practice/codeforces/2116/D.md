 ## 解决方案
 ## 问题理解

 我们得到一个长度为 n 的数组，它在 q 操作下演化。 每个操作采用两个索引 x 和 y，计算它们当前值中较小的一个，并将该值写入第三个位置 z。 在所有操作之后，我们被告知最终数组 b，并且我们必须重建可能产生 b 的任何可能的初始数组 a。 

重要的视角转变是，价值只会通过“最小”操作而向下移动。 任何操作都不能增加值，并且每个分配都会从两个来源之一复制信息。 因此，系统的行为就像一个定向信息流过程，其中每个位置都会被先前存在的两个位置中的最小值重复覆盖。 

约束很大：在测试中 n 和 q 最多为 3·10^5。 任何尝试显式模拟可能的初始状态或探索每个值的分配的解决方案都太慢。 每次测试我们都需要一些线性或接近线性的东西，因为总输入大小已经迫使 O(n + q) 行为。 

一个微妙的边缘情况是 b 中的约束与最小传播的单调性质相矛盾。 例如，如果稍后将一个索引用作另一个索引的源，则它会隐式地强制最终值不等式。 在示例中，如果 b2 > b1 但有一个操作 c2 = min(c1, c2)，则传播后 b2 不能超过 b1，因为此时 c2 始终最多为 c1。 

另一个常见的陷阱是假设每个位置都可以独立处理。 这是失败的，因为操作耦合了索引：单个位置可能通过最小分配链影响许多其他位置。 

## 方法

 直接的尝试是将 a 视为未知并向后模拟所有操作。 人们可能会尝试“撤消”每个分配，但 min 是不可逆的：知道 c_z = min(c_x, c_y) 并没有给出恢复 c_x 和 c_y 的唯一方法。 这使得向后模拟变得不明确。 

另一个天真的想法是猜测初始值并通过正向模拟进行验证。 这的可能性是指数级的，但立即不可行。 

关键的见解是扭转观点：不要问什么初始值可以产生最终值，而是问最终值对初始值施加了哪些约束。 每个操作 c_z = min(c_x, c_y) 意味着在所有操作之后，c_z 在赋值时最多只能是 c_x 和 c_y。 然而，由于值只会减少，最终的 b 值代表在所有传播中幸存下来的下限。 

我们可以将这个过程解释为构建一个有向约束图，其中每个操作都会强制最终值之间的不等式。 关键的观察是，我们可以通过逆序操作向后传播下界来构造候选初始数组，确保与所有最小约束的一致性。 如果出现矛盾，就没有解决办法。 

构建过程是从 b 作为基线开始，以相反的顺序向后“重播”操作，更新源的潜在上限，以便每个最小分配都可以产生观察到的最终状态。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟 | 指数| O(n) | 太慢了|
 | 反向约束传播| O(n + q) | O(n) | 已接受 |

 ## 算法演练

 我们反向处理操作，保持这样的想法：在每一步中我们都强制源和目的地之间的一致性。

1. 初始化数组 a 作为 b 的副本。 这表示在考虑所有约束后每个位置最终必须达到的最小值。 
2. 从最后到最先处理操作。 对于操作 (x, y, z)，我们知道在执行时，z 被设置为 min(x, y)。 完成所有操作后，此时 z 不能超过 x 或 y，因此 z 的最终值向后对 x 和 y 施加下界约束。 具体来说，x 和 y 都必须至少为 a[z]，否则 z 无法达到其最终值。 
3. 对于每个反向操作 (x, y, z)，更新：

 a[x] = 最大值(a[x], a[z])

 a[y] = max(a[y], a[z])

 这强制两个源都能够产生在 z 处观察到的最终值。 
4.处理完所有操作后，我们必须验证前向一致性。 我们从头到尾重放操作，计算如果将它们应用到构造的 a 中，数组会变成什么。 如果在任何时候 z 的计算值与 min(x, y) 不同，则构造无效。 
5. 如果验证通过，则输出a。 否则输出-1。 

前向验证步骤是必要的，因为后向传播仅强制执行下限可行性，而不是构造的值实际上再现了精确的转换序列。 

### 为什么它有效

 每个操作都会创建一个依赖关系：此时写入 z 的值永远不会大于 x 或 y。 向后运行可确保 x 和 y 都足够大以支持流过它们的所有值。 最终的正向模拟确保不会引入额外的意外减少。 下限传播和精确重播的结合保证了最小操作引起的每个约束都得到满足，而不会过度约束系统。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        b = list(map(int, input().split()))
        
        ops = []
        for _ in range(q):
            x, y, z = map(int, input().split())
            ops.append((x - 1, y - 1, z - 1))
        
        a = b[:]
        
        for x, y, z in reversed(ops):
            a[x] = max(a[x], a[z])
            a[y] = max(a[y], a[z])
        
        c = a[:]
        ok = True
        
        for x, y, z in ops:
            c[z] = min(c[x], c[y])
        
        if c != b:
            print(-1)
        else:
            print(*a)

if __name__ == "__main__":
    solve()
```该解决方案在概念上维护两个数组。 第一个 a 是通过向后传播约束获得的重建候选初始状态。 第二个 c 仅用于通过模拟前向过程进行验证。 

一个微妙的细节是我们与 b 进行比较，而不是与中间状态进行比较，因为只有最终的配置才重要。 另一个关键点是反向传播使用最大值，而不是最小值：我们提高下限，确保可行性而不是直接重建值。 

## 工作示例

 ### 示例 1

 输入：```
n = 2, q = 1
b = [1, 2]
op: (2, 1, 2)
```后向处理：

 | 步骤| 运营| 之前 | 更新 | 后|
 | --- | --- | --- | --- | --- |
 | 初始化| - | [1,2]| - | [1,2]|
 | 修订版1 | (2,1,2)| [1,2]| a2 强制 a2，a1 ≥ 2 | [2,2]|

 正向模拟：

 c1=2，c2=2，但预期 b=[1,2]，不匹配，因此无效。 

这表明，如果约束与固定的最终值冲突，仅向后传播是不够的。 

### 示例 2

 输入：```
n = 3, q = 2
b = [1,2,3]
ops: (2,3,2), (1,2,1)
```向后传播：

 | 步骤| 运营| 之前 | 更新 | 后|
 | --- | --- | --- | --- | --- |
 | 初始化| - | [1,2,3]| - | [1,2,3]|
 | 修订版2 | (1,2,1) | (1,2,1) | [1,2,3]| a2,a1 ≥ 1 | [1,2,3]|
 | 修订版1 | (2,3,2) | [1,2,3]| a2,a3 ≥ 2 | [1,2,3]|

 正向模拟准确地再现了 b。 

这证实了当不存在矛盾时，反向传播会产生一个稳定的分配，可以在所有最小操作中幸存下来。

 ## 边缘情况

 一种边缘情况是索引从不显示为 z，而是显示为 x 或 y。 在这种情况下，反向传播永远不会增加其值，因此它保持等于 b，这是正确的，因为它永远不会影响任何强制相等。 

另一种情况是自赋值，例如 c[z] = min(c[z], c[y])。 这创建了一个约束，即 z 必须至多为 y，并且向后传播通过最大更新以相反形式正确强制 a[z] ≤ a[y]。 

最后一个微妙的情况是长链，其中一个值流经多个位置。 该算法处理此问题是因为每个传播步骤仅强制执行可行性，并且重复的最大更新会积累最强的所需下限，而不会丢失中间依赖性。
