 ## 解决方案
 ## 问题理解

 我们得到一个仅由字符组成的二进制字符串`a`和`b`。 对于每个测试用例，我们必须找到任何连续的段，其数量`a`字符数恰好等于其数量`b`人物。 

输出不要求最长的平衡子串或平衡子串的数量。 任何有效的答案都可以接受。 如果不存在平衡子串，我们打印`-1 -1`。 

限制非常小。 每个字符串的长度最多为 50，并且最多可以有 1000 个测试用例。 即使是检查每个可能的子串的算法也能轻松满足时间限制，因为长度为 50 的字符串中只有大约 2500 个子串。 

这个问题有趣的部分是存在一个更简单的观察。 

考虑长度为 1 的字符串。```
a
```没有一个非空子串可以被平衡，因为每个子串只包含一个字符。 正确答案是`-1 -1`。 

一个常见的错误是假设每个字符串都包含长度至少为 2 的平衡子串。 

考虑一个所有字符都相同的字符串。```
aaaaa
```每个子串只包含`a`，所以没有一个可以有相同的计数`a`和`b`。 正确答案是`-1 -1`。 

粗心的实现可能只搜索偶数长度的子字符串，并错误地假设一个子字符串必须存在。 

另一个微妙的情况是字符串，例如：```
aba
```整个字符串不平衡，因为它包含两个`a`和一个`b`。 然而，子串`"ab"`是平衡的。 由于该问题接受任何平衡子串，因此我们应该一找到平衡子串就停止。 

## 方法

 暴力解决方案很简单。 枚举每一对`(l, r)`, 数数`a`和`b`在该子字符串内，并检查计数是否匹配。 由于有`O(n²)`子字符串和天真地计算字符`O(n)`时间，总复杂度为`O(n³)`。 

和`n ≤ 50`， 甚至`50³ = 125000`每个测试用例的操作是完全可管理的。 所以蛮力已经被接受了。 

真正的技巧来自于查看尽可能小的平衡子串。 

平衡子串必须包含相同数量的`a`和`b`。 最短的非空平衡子串的长度为 2，其唯一可能的形式是：```
ab
ba
```现在假设字符串中的某处存在平衡子字符串。 让我们检查一下它的前两个不同的字符。 由于字符串只包含`a`和`b`，任何相邻的不等对都是`"ab"`或者`"ba"`，这已经是平衡的了。 

这意味着我们永远不需要搜索长子字符串。 我们只需要找到两个不同的相邻字符即可。 

如果这样的对存在于位置`i`和`i+1`，然后是子串`[i, i+1]`已平衡，可立即退回。 

如果每一相邻对都相等，则整个字符串仅包含一个重复字符。 在这种情况下，不存在平衡子串。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 已接受 |
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取字符串。 
2. 扫描所有相邻的字符对。 
3. 对于每个位置`i`，检查是否`s[i] != s[i + 1]`。 
4. 如果找到这样的一对，则输出`i + 1`和`i + 2`使用从 1 开始的索引。 
5. 立即停止处理当前测试用例，因为`"ab"`和`"ba"`都是平衡子串。 
6. 如果扫描完成后没有找到任何不同的相邻字符，则输出`-1 -1`。 

步骤6正确的原因是没有相邻不同字符的二进制字符串必须完全由相同的字符组成。 这样的字符串不能包含相同数量的`a`和`b`在任何非空子字符串中。 

### 为什么它有效

 关键属性是每个相邻的不等对形成长度为 2 的平衡子串。 

如果算法返回位置`(i, i+1)`，子串是`"ab"`或者`"ba"`。 两者都包含一个`a`和一个`b`，所以答案是有效的。 

如果算法找不到相邻的不等对，则字符串中的每个字符都是相同的。 每个非空子字符串也由相同的字符组成，因此它不能同时包含这两个字符`a`和`b`。 因此不存在平衡子串。 

该算法永远不会输出无效的子串，并且永远不会错过现有的平衡子串。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    s = input().strip()

    found = False

    for i in range(n - 1):
        if s[i] != s[i + 1]:
            print(i + 1, i + 2)
            found = True
            break

    if not found:
        print(-1, -1)
```实施直接遵循观察结果。 

该循环检查每个相邻对一次。 当两个相邻字符不同时，对应的 length-2 子串是平衡的，因此立即打印答案。 

字符串内的索引是从 0 开始的，但问题需要从 1 开始的位置。 这就是为什么输出使用`i + 1`和`i + 2`。 

变量`found`跟踪是否已报告有效的子字符串。 如果循环结束时没有将其设置为`True`，该字符串只包含一个重复字符，答案必须是`-1 -1`。 

不存在溢出问题，因为该算法仅执行简单的索引操作。

 ## 边缘情况

 考虑输入：```
1
a
```相邻字符对上的循环永远不会执行，因为不存在相邻字符对。 算法到达末尾并打印`-1 -1`。 这是正确的，因为单个字符不能包含相同数量的`a`和`b`。 

考虑输入：```
5
aaaaa
```扫描检查`(a,a)`四次。 每次比较都是平等的，所以找不到答案。 算法打印`-1 -1`。 每个子串只包含`a`，因此不存在平衡子串。 

考虑输入：```
3
aba
```在`i = 0`，算法比较`a`和`b`。 它们不同，所以它输出`1 2`。 子串`"ab"`包含一个`a`和一个`b`，使其达到平衡。 整个字符串不平衡这一事实并不重要，因为任何有效的平衡子字符串都是可接受的。 

考虑输入：```
5
bbbba
```前三个相邻对是`(b,b)`。 在`i = 3`，这对是`(b,a)`，这是不同的。 算法输出`4 5`。 子串`"ba"`是平衡的，所以答案是正确的。 这种情况证实了字符串末尾附近的对被正确处理。
