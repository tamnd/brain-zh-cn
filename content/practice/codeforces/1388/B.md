 ## 解决方案
 ## 问题理解

 我们需要构建一个$n$- 位十进制数$x$。 

取每一位数字$x$，编写不带前导零的二进制表示形式，然后连接这些二进制字符串。 生成的二进制字符串称为$k$。 

之后，最后$n$的位$k$被删除。 剩余的前缀被解释为二进制数$r$。 

我们的目标是选择$x$以便$r$尽可能大。 如果有几个不同的$x$产生相同的最大值$r$，我们必须输出最小的这样$x$。 

输入仅包含长度$n$。 我们永远不需要重建$k$明确对于大值。 全部的总和$n$跨测试用例最多$2 \cdot 10^5$，因此任何在线性时间内处理每个测试用例的解决方案都足够快。 任何指数级的东西$n$，或任何试图搜索所有$n$数字，是完全不可能的。 

棘手的部分是理解删除最后一个的内容$n$位实际上意味着。 的价值$r$仅取决于截断后仍然存在的连接二进制字符串的前缀。 由于二进制数是按长度按字典顺序比较，然后按位进行比较，因此我们希望幸存的前缀尽可能大。 

有几种边缘情况很容易被误解。 

为了$n=1$，答案不是$9$。 如果$x=9$， 然后$k=1001$。 去掉最后一点叶子$100$。 如果$x=8$， 然后$k=1000$，并删除最后一位叶子$100$以及。 两者给出相同的最大值$r$， 但$8$较小，所以正确答案是：```
Input:
1

Output:
8
```另一个微妙的情况是$n=2$。 一个天真的想法可能是最大化每个数字和输出$99$。 然后：$$k = 1001\,1001$$删除最后两位叶子$100110$。 

为了$98$：$$k = 1001\,1000$$删除最后两位还剩下$100110$。 

由于两者达到相同的最大值$r$，我们必须选择较小的数字，即$98$。 

最后一个陷阱是假设只有最后一位数字重要。 为了$n=3$，答案是$998$， 不是$989$。 数字的位置决定了哪些位在截断后仍然存在，而最佳结构需要几个尾随的 8。 

## 方法

 蛮力的想法很简单。 枚举每一个$n$- 位数$x$,构建二进制字符串$k$，删除其最后一个$n$位，计算$r$，并保留最佳候选人。 

这是正确的，因为它检查了每种可能性。 不幸的是，即使对于$n=10$， 有$9 \cdot 10^9$候选人。 实际约束条件允许$n$最多$10^5$，因此穷举搜索不太可行。 

为了找到模式，我们需要了解如何$r$已形成。 

数字$8$和$9$很特殊，因为它们具有十进制数字中最长的二进制表示形式：$$8 = 1000,\qquad 9 = 1001.$$两者都贡献四位。 每隔一个数字最多贡献三位。 

存活前缀的长度$r$是$$|k| - n.$$为了最大化二进制数，首要任务是最大化其长度。 由于每个数字最多贡献四位，因此我们应该尽可能让每个数字贡献四位。 这意味着每个数字都应该是$8$或者$9$。 

现在所有候选者都有相同的二进制总长度$4n$，所以每个结果$r$有长度$3n$。 比较变成字典顺序。 

观察二进制字符串$8$和$9$仅最后一位不同：$$1000,\qquad 1001.$$最后一个$n$连接的位被丢弃。 任何完全落在删除的后缀内的位都不会影响$r$。 

假设我们放置一个$8$接近尾声了。 它的最后一位是$0$而不是$1$由一个提供$9$。 如果无论如何都删除了该不同的位，则更改$9$到一个$8$不影响$r$，同时制作$x$较小。 

因此，最优策略是：

 1. 仅使用数字$8$和$9$。 
2. 保持尽可能多的前导数字等于$9$，因为它们的不同位保留在内部$r$。 
3. 将最大可能的后缀替换为$8$，因为这些数字的不同位位于丢弃的部分内。 

可以更改多少个尾随数字$8$？ 

每个数字贡献四位。 丢弃的后缀有长度$n$。 数字的区别位是其第四位。 我们可以安全地将该位隐藏在删除的后缀中$$\left\lceil \frac{n}{4} \right\rceil$$末尾的数字。 

因此答案是：$$\underbrace{99\ldots9}_{n-\lceil n/4\rceil} \underbrace{88\ldots8}_{\lceil n/4\rceil}.$$这就是著名的 Codeforces 解决方案。

 ## 算法演练

 1. 阅读$n$。 
2. 计算$$m = \left\lceil \frac{n}{4} \right\rceil.$$这是可以更改的尾随数字的数量$9$到$8$不影响最大值$r$。 

1.第一个$n-m$位置应该是数字$9$。 

这些数字贡献了保留在幸存前缀内的位，因此使它们$9$给出字典顺序上最大的可能$r$。 
2.最后一个$m$位置应该是数字$8$。 

它们的区别位位于丢弃的后缀内，因此替换$9$经过$8$保持$r$制作时不变$x$较小。 
3. 输出结果字符串。 

### 为什么它有效

 除以下任意数字$8$或者$9$贡献少于四位，减少了总长度$k$。 自从$r$有长度$|k|-n$，这会立即产生一个较短的二进制数，并且不是最佳的。 

在将自己限制在数字之后$8$和$9$，每个数字恰好贡献四位。 它们之间的唯一区别是二进制表示的最后一位。 最后一个$n$连接的位被丢弃，因此最终的区别位$\lceil n/4\rceil$数字从未出现在$r$。 这些数字可能会改变$9$到$8$不影响$r$。 

任何较早的数字仍然有影响$r$。 更改这样的数字$9$到$8$替换幸存的位$1$经过$0$， 制作$r$较小。 因此，所有先前的职位必须保留$9$。 

在产生最大可能的所有数字中$r$，这种结构最小化$x$因为它取代了所有可能的尾随$9$经过$8$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
ans = []

for _ in range(t):
    n = int(input())
    eights = (n + 3) // 4
    nines = n - eights
    ans.append("9" * nines + "8" * eights)

print("\n".join(ans))
```实现直接遵循数学特征。 

表达式`(n + 3) // 4`计算$\lceil n/4 \rceil$使用整数运算。 这是唯一重要的细节。 

答案的第一部分包含`n - eights`的副本`'9'`。 第二部分包含`eights`的副本`'8'`。 

不构造二进制字符串。 该解决方案仅构建最终的十进制答案，这就是它在输出大小方面保持线性的原因。 

一个常见的错误是使用`n // 4`而不是天花板划分。 例如，当`n = 1`，楼层划分给出`0`，生产`"9"`而不是正确答案`"8"`。

 ## 边缘情况

 考虑最小的输入：```
1
1
```该算法计算：$$\left\lceil \frac{1}{4} \right\rceil = 1.$$所以答案是`8`。 使用楼层划分会错误地产生`9`。 构造正确地处理了这个边界。 

考虑：```
1
4
```该算法计算：$$\left\lceil \frac{4}{4} \right\rceil = 1.$$输出是：```
9998
```只有最后一位数字属于可移动区域。 任何较早的替换`8`会减少结果值$r$。 

考虑：```
1
5
```该算法计算：$$\left\lceil \frac{5}{4} \right\rceil = 2.$$输出是：```
99988
```此案例捕获了最常见的相差一错误。 使用楼层除法只会产生一个尾随`8`，这不是所有最优结构中的最小有效答案。 

最后，对于非常大的值，例如：```
1
100000
```该算法从不构建二进制表示，也从不执行任何昂贵的计算。 它只是输出 75,000 个 9，然后输出 25,000 个 8，在输出大小上保持线性。
