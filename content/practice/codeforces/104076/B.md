 ## 解决方案
 ## 问题理解

 两个人正按照固定的顺序穿过狭窄的山洞。 第一个人庞总是领先，第二个人受一开始就落后一个单位。 两者都以离散的时间步长向前移动，但如果他们的火炬当前正在燃烧，他们只能在一秒钟内移动。 一旦火炬耗尽燃料，拥有者必须停下来并花固定的秒数来补充燃料，在此期间他们不能行走。 重要的是，火炬不能提前补充燃料； 在开始加油之前，它必须完全燃尽。 

每一秒都有严格的顺序：如果庞的火炬被点燃，那么他首先移动，然后如果他的火炬被点燃，则寿尝试移动。 因为庞总是领先并阻止超车，所以寿的运动受到他自己的火炬时间表的限制，而不是超出初始偏移量的空间相互作用。 

对于每个查询时间 qi，我们都会被问到 Shou 从他的起始位置移动了多远，假设两个步行者都表现得很贪婪，这意味着只要他们的火把允许，他们就会步行。 

核心困难在于运动不是连续的或独立的。 每个人在固定长度的“燃烧阶段”和固定长度的“加油阶段”之间交替，并且这些阶段根据先前的消耗随时间变化。 该系统是确定性的，但具有周期性，并且查询可能非常大，最多可达 10^16，因此每秒直接模拟是不可能的。 

这些约束使这个结构变得清晰。 最多可以有 10^5 个测试用例，但所有循环参数和查询的总和以 10^6 为界。 这强烈表明任何解决方案都必须在线性时间内预处理每个测试用例，并在恒定或对数时间内回答每个查询。 任何随着时间 qi 迭代的东西都是立即不可行的，因为 qi 可以达到 10^16。 

初始条件出现了一个微妙的边缘情况：两个火炬都已在零时间加完燃料。 这意味着两者都以满负荷启动燃烧阶段。 另一个不明显的点是每秒内的严格排序：Pang 在 Shou 之前移动，这可能会影响 Shou 在幼稚模拟中同步很重要的边缘情况下是否“允许”移动。 然而，由于 Shou 的移动不会影响 Pang，反之亦然，因此仅当试图错误地模拟位置相关的阻挡时，顺序才重要。 

最后的边缘情况是火炬燃烧一秒钟或补充燃料一秒钟。 在这种情况下，如果假设连续间隔而没有仔细的模运算，则简单的周期检测可能会使相位边界错位。 

## 方法

 暴力解释很简单。 我们模拟每一秒，跟踪两人当前燃烧阶段还剩多少秒，以及他们是否正在加油。 每一步都会减少燃油或加油计时器，并在可能的情况下增加位置。 这是正确的，因为它严格遵守字面规则。 但是，每个查询最多可达 10^16，因此不可能逐秒进行模拟。 即使我们跨查询重复使用模拟，单个测试用例也可能需要大约 10^16 次操作。 

关键的观察是每个人的行为都是独立且周期性的。 对于每个火炬，该模式是一个固定的循环：燃烧 1 秒，然后补充燃料 b 秒，然后重复。 在燃烧过程中，每秒恰好获得一个距离单位。 加油期间，不发生任何运动。 因此，问题归结为计算长度为 q 的前缀中出现了多少“活动秒”（燃烧秒）。 

对于每个人，我们可以将时间线建模为长度为 (a + b) 的重复块。 在每个完整的周期中，它们精确地移动一步。 对于较长的时间 q，我们计算适合多少个完整周期，然后处理剩余的部分周期。 这给出了他们行走的总秒数。

唯一的微妙之处在于庞的日程安排是否会干扰寿。 并不影响受的移动能力，因为受的移动只取决于他自己的火炬状态和他无法超越的规则。 由于庞总是先行并保持领先，所以寿的约束减少为“只要火炬燃烧，寿就移动”，与庞的确切时间无关。 因此我们可以孤立地对待Shou。 

这在预处理后将每个查询减少为简单的算术计算。

 ## 算法演练

 ###受的动作模型

 1. 将Shou的火炬时间表视为长度为a2 + b2的重复循环。 

在每个周期的前 a2 秒内，他每秒移动一个单位。 在接下来的 b2 秒内，他没有移动，因为他正在加油。 
2. 对于查询时间 q，计算 q 适合多少个完整周期。 

这是 q // (a2 + b2)。 每个完整周期恰好贡献 a2 单位的运动。 
3. 使用 q % (a2 + b2) 计算完整循环后的剩余时间。 

该剩余窗口可以覆盖部分燃烧阶段或部分加油阶段。 
4. 将 min(a2, 余数) 添加到答案中。 

如果剩余时间完全位于燃烧段内，则受贡献所有剩余秒数。 否则，他只贡献燃烧的部分。 
5. 将总运动输出为 full_cycles * a2 + min(a2, 余数)。 

### 为什么它有效

 Shou的状态演化仅取决于他内部的周期性火炬周期，这是确定性的，不依赖于位置或相互作用。 时间线划分为固定结构的不相交循环，并且在每个循环内对运动的贡献是固定的。 任何时间前缀都唯一地分解为完整周期加上周期前缀，因此对这些不相交间隔上的贡献求和可以准确地保持正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        a1, b1, a2, b2, n = map(int, input().split())

        cycle = a2 + b2
        burn = a2

        for _ in range(n):
            q = int(input())

            full = q // cycle
            rem = q % cycle

            ans = full * burn + min(burn, rem)
            out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```该解决方案仅隔离 Shou 的参数，因为 Pang 不影响 Shou 的移动计数。 关键的计算是将时间分为完整周期和余数，然后将每个周期转换为燃烧的秒数。 

整数算术是安全的，因为 q 最大可达 10^16，但 Python 可以自然地处理它。 使用快速输入和预累积输出可避免多达 10^5 个测试用例的开销。

 ## 边缘情况

 一个关键的边缘情况是 q 恰好落在循环边界上。 例如，当 a2 = 5 且 b2 = 2 时，当 q = 7 时，余数为零。 该算法产生 full_cycles * 5 + 0，正确捕获没有部分燃烧会超出完整周期。 

另一种情况是 q 小于 a2 时。 在这种情况下，full_cycles 为零，min(a2, q) 直接返回 q，这意味着受始终处于燃烧阶段，每秒都会移动。 这避免了任何特殊分支的需要。 

最后一种情况是当 b2 = 0 时。循环变为纯粹燃烧，因此循环 = a2 并且每秒都会产生运动。 该公式简化为 q，因为 full_cycles * a2 + min(a2, 0) 干净地简化为 q，符合直觉。
