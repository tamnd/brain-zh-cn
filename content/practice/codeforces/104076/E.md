 ## 解决方案
 ## 问题理解

 我们得到从 1 到 n 的数字排列和固定的段长度 k。 对于排列内长度为 k 的每个连续块，我们计算其总和。 要求是所有这些窗口总和必须具有相同的奇偶性，这意味着每个这样的总和要么总是偶数，要么总是奇数。 

任务不是构造排列，而只是确定每个测试用例是否至少存在一个有效排列。 

约束条件非常大，n 和 k 最多为 10^9，测试用例最多为 10^5。 任何试图显式模拟排列或检查窗口的解决方案都是立即不可能的。 即使每个测试用例进行线性扫描也已经太慢了，因此答案必须来自 n 和 k 上的直接结构条件。 

当 k 等于 1 时，会出现微妙的边缘情况。每个窗口都包含一个元素，因此该条件强制排列中的所有值共享相同的奇偶校验。 由于当 n ≥ 2 时，1 到 n 的排列始终包含奇数和偶数，因此这是不可能的。 例如，当 n = 3 且 k = 1 时，像 [1, 2, 3] 这样的任何排列都会产生窗口和 1, 2, 3，它们不共享奇偶校验，因此正确答案为“否”。当 n = 1 且 k = 1 时，只有一个窗口，因此条件基本满足，答案为“是”。 

另一个潜在的陷阱是假设大 k 总是使情况更容易。 例如，当 k = n 时，只有一个窗口，因此无论排列如何，条件始终成立。 

## 方法

 蛮力视角首先选择一个排列并检查所有长度为 k 的子数组。 对于每个测试用例，这将涉及计算 n − k + 1 个窗口和，除非使用前缀和，否则每次都需要 O(k) 时间。 即使使用前缀和，每次测试仍然需要 O(n) 时间，当 n 达到 10^9 时这是不可能的。 

关键的简化来自于相邻窗口的比较。 令 S_i 为从位置 i 开始的子数组的总和。 那么连续窗口之间的差异是

 S_{i+1} − S_i = p[i+k] − p[i]。 

由于我们只关心奇偶校验，减法的行为类似于加法模 2，因此所有 S_i 具有相同奇偶校验力的条件

 p[i] == p[i+k] (mod 2)。 

这意味着恰好被 k 个位置分隔的元素必须具有相同的奇偶校验。 因此，该数组根据索引模 k 被划分为 k 个独立的链，并且每个链必须完全由单个奇偶校验的数字组成。 

那么问题就变成了：我们能否为这 k 个位置组中的每一个分配全奇数或全偶数，使得奇数槽的总数等于 1 到 n 中奇数整数的数量？ 

至此，结构就变得简单了。 k 个组的大小最多相差 1，我们可以选择哪些组是“奇数组”。 因为可用的组大小形成连续的结构（只有floor(n/k)和ceil(n/k)），所以只要我们不被迫陷入矛盾，就可以实现组大小的每个目标总和。 

当 k = 1 时，唯一真正的障碍出现。在这种情况下，存在一个包含所有位置的组，并且它必须是全奇数或全偶数。 这将要求从 1 到 n 的所有数字共享相同的奇偶校验，除非 n = 1，否则这是不可能的。 

对于每个 k ≥ 2，选择哪些组采用奇数的灵活性足以匹配所需的奇数整数的数量。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力窗口检查 | 每次测试 O(nk) 或 O(n) | O(1) | O(1) | 太慢了|
 | 奇偶分解洞察 | 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

1. 检查 k 是否等于 1。如果等于，则条件强制排列中的每个元素具有相同的奇偶校验。 这仅在 n 等于 1 时才有可能，因为任何更大的排列都包含奇数和偶数。 
2. 如果 k 大于或等于 2，则可构造性始终是可能的。 奇偶校验约束仅强制索引类内的模 k 相等，并且这些类始终可以以与所需的全局计数匹配的方式分配奇数和偶数角色。 
3. 除 k 等于 1 且 n 大于 1 时外，所有情况均输出“Yes”。 

### 为什么它有效

 奇偶校验约束将数组简化为独立的索引类，其中位置 i、i + k、i + 2k 等处的所有元素必须共享奇偶校验。 这些类是唯一对有效性重要的结构。 由于我们可以自由地为每个类分配奇偶校验，因此问题就变成了在 k 个可调整组之间划分所需的奇数计数。 这种划分唯一不可能发生的情况是只有一组时，这种情况恰好发生在 k = 1 且 n > 1 时。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        if k == 1 and n > 1:
            print("No")
        else:
            print("Yes")

if __name__ == "__main__":
    solve()
```实现直接编码结构结论。 唯一的条件分支对应于所有元素必须位于单个奇偶校验类中的退化情况。 不需要模拟或构造，因为问题完全归结为模块化索引图是否具有多个组件。

 我们有两个位置类别：索引 (1,3) 和 (2,4)。 每个班级必须有统一的平等。 1 到 4 中奇数的个数为 2，因此我们可以将一类分配给奇数，将另一类分配给偶数。

 | 平价要求| 位置 i 和 i+2 共享平价 |
 | 作业 | 一类奇数，一类偶数|
 | 结果| 有效 |

 这表明类分配的灵活性允许平衡奇偶校验计数。 

### 示例 2

 输入：n = 3，k = 1

 有一个类包含所有职位。 所有元素必须共享奇偶校验，但集合 {1,2,3} 同时包含奇数和偶数值。 

| 步骤| 观察|
 | --- | --- |
 | k 检查 | k = 1，单类 |
 | 约束| 所有值必须具有相同的奇偶校验 |

 这表明所有结构都崩溃为单个强制奇偶校验组。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

 ## 边缘情况

 最重要的边缘情况是 k = 1 时。在这种情况下，每个窗口都是单个元素，因此排列中的所有数字必须共享相同的奇偶校验。 对于任何 n > 1，这会立即失败，因为排列同时包含奇数和偶数。 算法正确地识别了这一点并输出 No。 

例如，当输入 n = 2、k = 1 时，代码将进入特殊条件并拒绝这种情况。 如果我们追踪逻辑，单个类包含两个位置，迫使两个数字具有相同的奇偶性，这与集合 {1, 2} 的结构相矛盾。 

当 k ≥ 2 时，即使像 k = n 这样的极端值也会正确运行。 该算法会立即接受它们，因为只有一个窗口，因此不会出现奇偶校验冲突。
