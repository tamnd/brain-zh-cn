 ## 解决方案
 ## 问题理解

 我们得到了从 1 到 n 的整数排列。 我们从左到右读取数字，当我们看到每个数字时，我们必须立即将其放入 m 个堆栈中的一个。 放置是永久性的，因此一旦将元素推入堆栈，它就会保留在那里，直到弹出整个堆栈。 

当所有的推送完成后，我们就可以开始弹出了。 规则是我们选择一个堆栈并不断从中弹出，直到它变空，然后才能切换到另一个堆栈。 当堆栈被弹出时，它以标准的后进先出方式运行。 

目标是选择如何将元素分配到堆栈以及如何对堆栈弹出进行排序，以便全局输出序列恰好为 1、2、3，最多为 n。 我们希望使用尽可能少的堆栈来实现这一目标。 

跨测试的约束 n 高达 5×10^5 意味着每个测试方法需要 O(n log n) 或 O(n)。 任何尝试模拟所有堆栈分配或搜索分区的解决方案都会立即失败，因为即使 O(n^2) 也远远超出了可行的限制。 

一个微妙的问题是出栈阶段受到堆栈边界的限制。 如果选择堆栈，则在切换之前必须将其完全清空。 这对单个堆栈内的元素必须如何在值上相互关联产生了强大的排序约束。 

暴露约束的一个小例子是排列 [3, 1, 2]。 如果我们尝试按入栈顺序将 3 和 1 放入同一个堆栈中，我们会得到入栈序列 [3, 1]，它将以 [1, 3] 的形式弹出。 它不能出现在所需的全局顺序 1、2、3 中，因为相对于其他堆栈，3 将出现在 2 之前的错误位置。 这种反转是核心难点。 

## 方法

 思考这个问题的强力方法是将 n 个元素中的每一个分配给 m 个堆栈之一，然后模拟出栈阶段来检查是否可以实现排序输出。 即使对于固定分配，验证正确性也需要模拟堆栈行为并确保在每一步中下一个所需的数字出现在我们选择清空的某个堆栈的顶部。 在最坏的情况下，分配的数量为 m^n，即使限制 m 也无法使其可行。 

关键的简化来自于查看单个堆栈强制执行的结构。 在一个堆栈中，元素的弹出顺序与其入栈顺序相反。 由于最终输出必须从 1 增加到 n，因此每个堆栈内的反向压入顺序本身也必须增加。 这意味着当我们查看堆栈内的压入顺序时，这些值必须形成严格递减的序列。 

因此，每个堆栈都被迫包含一个排列的子序列，该子序列的值随着到达时间而递减。 问题变成了分区任务：将排列拆分为最小数量的递减子序列。 

这是经典的二元性结果。 划分序列所需的最小递减子序列数等于最长递增子序列的长度。 直觉是，每个递增链必须放入不同的堆栈中，因为单个堆栈在反转时无法保留递增顺序。 

因此，我们不是显式地构建堆栈，而是计算给定排列的 LIS 的长度。 这个值就是答案。

 ## 算法演练

1. 我们从左到右处理排列，并维护一个代表递减子序列的最佳可能“栈顶”的结构。 
2. 对于每个传入值 x，我们希望将其放入一个堆栈中，以保持该堆栈的序列严格递减。 这相当于找到一个当前顶部大于 x 的堆栈，因为将 x 放置在较大顶部下方可以保留入栈序列中的递减顺序。 
3. 在所有有效堆栈中，我们选择具有最小可能顶部值且仍大于 x 的堆栈。 这种贪婪的选择保留了未来元素的灵活性，因为它为更大的未来值保留了更大的顶部。 
4. 如果不存在这样的堆栈，我们用 x 开始一个新堆栈。 这对应于增加递减子序列的数量。 
5. 我们维护一个递增排序的栈顶数组。 每次更新都会替换一个值或附加一个新值，这可以使用二分搜索来实现。 
6.处理完所有元素后，栈的数量正好是这个结构体的大小。 

这种贪婪选择起作用的原因是每个堆栈代表原始顺序的递减子序列。 通过始终将元素放置在最合适的现有堆栈上，我们可以确保当现有堆栈仍可容纳该元素时，不会创建不必要的新堆栈。 

### 为什么它有效

 在任何时候，所维护的结构都表示由处理后的前缀形成的递减子序列的结束值的最小可能集合。 每次放置一个元素时，我们要么扩展一个子序列，要么用较小的值替换其结束值，这为将来的扩展保留更多空间。 这正是应用于逆序解释的 LIS 计算的耐心排序不变量。 因此，所需的堆栈数量是强制分离的最长链的长度，其对应于排列的 LIS 长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        a = list(map(int, input().split()))

        piles = []

        for x in a:
            # we want first pile top > x, so we maintain increasing piles
            # use binary search on piles for first > x
            l, r = 0, len(piles)
            while l < r:
                mid = (l + r) // 2
                if piles[mid] > x:
                    r = mid
                else:
                    l = mid + 1

            if l == len(piles):
                piles.append(x)
            else:
                piles[l] = x

        print(len(piles))

if __name__ == "__main__":
    solve()
```该实现维护一个数组`piles`其中每个条目表示结束递减子序列的堆栈的当前最小可能顶部值。 二分查找找到顶部大于当前值的第一个堆，这是扩展该子序列的正确位置。 

如果不存在这样的堆，则创建一个新的堆。 这是答案增加的唯一情况。

 ## 边缘情况

 像 [5, 4, 3, 2, 1] 这样的完全递减排列会产生一个堆。 每个新元素都可以替换之前的顶部元素，因此不会创建额外的堆栈。 

像 [1, 2, 3, 4] 这样的完全递增排列会迫使算法在每一步创建一个新的堆，因为现有的堆栈顶部都不大于当前元素。 这直接对应于需要 n 个堆栈，因为没有两个元素可以共存于同一递减子序列中。 

诸如 [2, 1, 4, 3] 之类的混合情况显示了替换如何避免不必要的堆栈创建。 元素 1 替换 2，稍后 3 替换 4，使堆栈数量最小为 2，这与序列的 LIS 结构匹配。
