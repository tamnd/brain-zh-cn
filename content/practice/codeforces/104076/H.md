 ## 解决方案
 ## 问题理解

 我们从间隔的集合开始。 每个区间代表数轴上的一个连续范围。 该过程反复将两个现有间隔合并为一个新间隔。 在合并过程中，我们从第一个区间中选择一个实数，从第二个区间中选择一个实数，唯一的限制是第一个选择的值必须严格小于第二个值。 删除两个原始间隔，并插入由这两个选定值定义的新间隔。 

重复此操作直到只剩下一个间隔，对和内部点的不同选择可能会导致不同的最终间隔。 任务是确定可以产生多少个不同的最终间隔。 

因此，问题不在于模拟该过程，而在于了解在任意多次此类合并之后，哪些端点可以作为最终结果出现。 

输入由多个测试用例组成。 每个测试用例最多提供 100000 个间隔，每个间隔的整数端点最多为 10^9。 在所有测试用例中，间隔总数最多为 100000。 

这立即排除了任何尝试模拟合并或探索组合的解决方案。 每个测试用例中的 n 的任何平方都会失败，因为 10^5 的平方已经是 10^10 次运算。 

一个微妙的边缘情况来自这样一个事实：合并操作允许选取区间内的任何点，而不仅仅是端点。 例如，对于区间 [1, 100] 和 [2, 3]，我们不限于像 1 或 100 这样的端点，而是可以选择内部的任何实际值。 仅考虑端点的天真解释会错过有效的构造。 

另一个陷阱是假设过程是确定性的，或者最终间隔由最小左端点和最大右端点唯一定义。 这是错误的，因为不同的合并顺序可能会限制可以结转哪些值。 

## 方法

 暴力破解的想法是模拟合并过程。 在每个步骤中，选择两个间隔，枚举 x 和 y 的所有可能选择，并跟踪结果间隔。 这很快就会呈指数增长，因为每次合并都会引入一系列选择，甚至离散到端点也会导致间隔组合方式的组合爆炸。 n−1 次合并后，可能状态的数量会远远超出任何可行的界限。 

关键的观察结果是，除了选择区间内任何值的能力之外，合并操作不会保留内部结构。 一旦两个区间合并，所得区间的行为就像从某个可实现的最小值到某个可实现的最大值的连续范围，并且未来的操作仅取决于这些极端值。 每个区间内的历史变得无关紧要，除了哪些值可以充当左端点和哪些可以充当右端点。 

这将问题简化为推理哪些值可以显示为最终间隔的全局左端点以及哪些值可以显示为全局右端点。 任何最终间隔都是通过选择一个值作为最小值和一个值作为最大值来确定的，其中这两个值必须来自不同的原始间隔，因为每次合并都结合了不同的源。 

这导致了一种简化：我们只关心间隔对，其中我们将一个间隔中的值作为最终的左端点，将另一个间隔中的值作为最终的右端点，其中左侧严格小于右侧。 由于区间内的任何值都是可用的，每个区间贡献一个完整的连续范围，因此只有端点对于可行性比较很重要。 

因此，问题就变成了计算有多少有序区间对可以产生有效的不等式 li < rj。

 ## 算法演练

 我们将每个区间 [li, ri] 重新表述为贡献两个可用值：任何候选左端点都位于 [li, ri] 中的某个位置，对于右端点也是如此。 唯一的全局要求是最终的左值严格小于最终的右值，并且它们必须来自不同的区间。 

计数任务变成：有多少对区间 (i, j) 允许我们在区间 i 中选取一些 x，在区间 j 中选取一些 y，使得 x < y。 

由于 x 可以是 [li, ri] 中的任何值，因此最强的约束来自最坏情况的选择：间隔 i 可以贡献与 ri 一样大或与 li 一样小的贡献，具体取决于合并树中的方向。 然而，因为我们正在计算某些有效构造的存在性，所以检查是否存在满足 li < rj 的值对就足够了，这相当于比较端点。 

这导致直接组合减少。 

1. 将所有区间的左端点收集到数组 L 中，将右端点收集到数组 R 中。 
2. 对两个数组独立排序。 
3. 对于每个区间 i，我们要统计有多少个区间 j 满足 li < rj。 
4. 使用已排序 R 上的指针扫描可能的右端点。对于每个 li，计算有多少个 rj 严格大于 li。 
5. 对所有 i 的这些计数求和，确保 i 和 j 不同，这是自动处理的，因为间隔相等并不满足两个方向上的严格不等式。 

### 为什么它有效

 基本的不变量是合并过程从不限制可以向上携带超出间隔端点的值集。 合并区间的每个子树始终可以实现其当前聚合区间内的任何值，并且聚合不会产生空洞或离散限制。 因此，构建最终对的可行性仅取决于间隔之间的端点排序，而不取决于合并历史或结构。 这将问题分解为区间边界的纯粹成对比较。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        L = []
        R = []
        intervals = []
        
        for _ in range(n):
            l, r = map(int, input().split())
            L.append(l)
            R.append(r)
            intervals.append((l, r))
        
        L.sort()
        R.sort()
        
        j = 0
        ans = 0
        
        for l in L:
            while j < n and R[j] <= l:
                j += 1
            ans += (n - j)
        
        print(ans)

if __name__ == "__main__":
    solve()
```该代码将左端点和右端点分开，因为我们最终需要的条件是所选左值和所选右值之间的纯粹不等式。 对两个数组进行排序允许线性扫描，其中对于每个可能的左端点，我们计算有多少个右端点严格更大。 

指针 j 仅向前移动，因为 R 已排序，确保每个元素都被处理一次。 这避免了 O(n^2) 嵌套循环。 

一个微妙的点是严格的不平等。 循环前进超过所有 rj ≤ l，确保仅计算有效的 rj > l。

 考虑一小组间隔。 

输入：```

1 2

```我们计算 L = [1, 3, 5] 和 R = [2, 4, 6]。 

| 我| j 之前 | R[j] 条件 | j 之后 | 贡献 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 2 > 1 立即成立 | 0 | 3 |

这表明每对间隔都是有效的，因为后面间隔的每个左端点都小于每个右端点。

 ## 边缘情况

 诸如 [1,2] 之类的单个区间情况表明该算法正确返回零，因为没有第二个区间可以形成一对，并且扫描自然不会产生任何贡献。 

像 [1,10]、[2,9]、[3,8] 这样的完全嵌套配置证明了每个左端点仍然小于多个右端点，并且该算法正确地计算所有有效的交叉对，而不会重复计算。 

严格的不相交区间链（例如 [1,2]、[3,4]、[5,6]）表明，即使没有重叠，每个较早的左端点仍然与较晚的右端点兼容，并且基于不等式的计数仍然捕获所有有效的结构。
