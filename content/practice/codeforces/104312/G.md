 ## 解决方案
 ## 问题理解

 我们得到了多组卡片，其中每张卡片都有一个称为怪异数的整数标签。 从这个初始集合中，我们希望得到一个非常严格的最终集合：它必须包含从 1 到某个选定值 K 的每个怪异数字的一张卡片，除此之外别无其他。 这同时意味着两件事。 首先，1 到 K 范围内的每个整数必须恰好出现一次。 其次，我们不允许保留任何价值超出此范围的卡。 

我们可以通过两种方式修改我们的集合。 我们可以以每张卡的成本 B“购买”任何缺失的怪异号码。 我们还可以“以旧换新”任何现有的卡，将其转换为不同的怪异号码，每次操作的成本为 A。 交易使卡牌数量保持不变，而购买会增加数量，但最终要求无论如何都会强制卡牌数量与 K 匹配，因此实际上每张卡牌最终都必须成为 1..K 中的不同值。 

真正的目标是选择K并决定保留哪些现有卡牌、改造哪些卡牌以及购买哪些隐含目标值，以便最终结构是成本最小的1..K的完美前缀排列。 

约束最大为 N ≤ 10^5，值最大为 10^6，因此任何尝试每个 K 并进行昂贵的重新计算的解决方案都会太慢。 在最坏的情况下，对可能的 K 进行二次扫描或重复频率重建将导致大约 10^10 次操作，这在一秒钟内是不可行的。 

当存在重复项时，会出现微妙的边缘情况。 例如，如果我们有单个值的许多副本，则最好交易额外的而不是购买缺失的数字，反之亦然，具体取决于 A 是否大于 B。当 A > B 时会出现另一种边缘情况，因为此时交易严格地比购买更糟糕，因此最佳解决方案应该有效地忽略所有现有的卡，除了那些可能已经匹配所需值的卡。 

## 方法

 一种简单的方法是固定目标 K，然后计算将当前多重集精确转换为 {1, 2, ..., K} 的成本。 对于每个 K，我们会计算 1..K 中我们已经拥有多少张、缺少多少张以及必须将多少张额外的牌“转换”为所需的值。 如果我们对每个 K 独立地进行模拟，则每次计算的成本为 O(N)，而对 N 以内的所有 K 执行此操作会得到 O(N^2)，这在最坏的情况下约为 10^10 次操作，显然太慢了。 

关键的观察结果是问题的结构在 K 中是单调的。随着 K 增加 1，我们只添加一个新的所需值。 这意味着我们可以维护有关我们已经满足了多少个不同的要求值以及有多少张卡被“浪费”或“额外”的运行信息。 如果我们跟踪频率并逐渐扩展 K，则成本结构将变为线性。 

另一个重要的简化来自贸易规则。 每张现有的卡牌如果与目标集匹配，则可以保留，或者以成本 A 进行转换。但如果缺少某个值，我们可以转换额外的卡牌或购买新的卡牌。 这就产生了一个按值决定：对于 1..K 中的每个数字，我们只需要一份副本，并且我们选择最便宜的方式来获取它：要么从现有的未使用的卡（通过交易链），要么直接购买。 

这导致了经典的贪婪观点：我们从 1 向上扫描 K，维护我们当前拥有多少张可以重新利用的“剩余”卡，并在每一步决定是使用剩余还是支付 B。如果使用剩余，则成本 A；如果使用剩余，则成本 A；如果使用剩余，则成本 A。 如果没有，我们支付B。最好的策略仅取决于我们到目前为止积累了多少张剩余卡牌。 

因此，问题简化为跟踪值的频率并维持不断增长的前缀要求，同时始终为每个所需位置使用最便宜的可用源。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 通过完全重新计算对 K 进行暴力破解 | O(N^2) | O(N^2) | O(N) | 太慢了|
 | 增量前缀+剩余跟踪| O(N log N) 或 O(N) | O(N) | 已接受 |

 ## 算法演练

 我们首先将输入压缩为怪异数的频率图。 这告诉我们有多少“已经正确”的项目具有任何价值。 

然后我们按顺序模拟构建目标集 1、2、3、…。 

1. 按照所需怪异数从 1 向上递增的顺序对值进行排序或以其他方式迭代，从而维护我们拥有可分配的可用卡牌数量。 
2. 维护一个变量`surplus`，代表我们拥有的卡片在其原始位置不需要但可以转换成其他东西。 
3. 对于从 1 开始向上的每个值 i，检查输入频率表中是否已经至少有一张值为 i 的卡。 如果是，我们使用它并增加剩余量（频率[i] - 1），因为只有一份副本被作为“自然匹配”消耗，其余的成为灵活资源。 
4. 如果频率[i]为零，我们必须从其他地方获取它。 如果剩余 > 0，我们使用一张剩余卡并支付成本 A 将其转换为值 i。 否则我们必须直接以成本B购买。 
5. 累积每个 i 的成本并继续，直到达到最佳停止为止。 由于添加较大的 K 总是至少会增加 B 成本或 A 成本，因此一旦继续没有好处，我们就停止，这在实现中是通过迭代到安全界限来处理的。 
6. 答案是在所有前缀上观察到的最小成本。 

关键的不变量是，在步骤 i，剩余正确地代表了先前看到的额外卡的数量，这些卡仍然可以在不违反 1..i−1 的唯一性约束的情况下重新分配。 每次我们进行到 i 时，我们都会最优地决定是消耗剩余还是直接支付，并且除了通过剩余规模之外，未来的决定不取决于我们如何解决之前的问题。 

正确性如下，因为一旦我们确定了有多少个可重用的额外项，每个值 i 都是独立的； 每一步的贪婪选择都可以最大限度地降低局部成本，并为未来的步骤保留可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    N, A, B = map(int, input().split())
    arr = list(map(int, input().split()))

    from collections import Counter
    freq = Counter(arr)

    surplus = 0
    cost = 0
    best = float('inf')

    # We try building prefix 1..K; K won't need to exceed N significantly
    for k in range(1, N + 2):
        if freq.get(k, 0) > 0:
            # use one, extras become surplus
            surplus += freq[k] - 1
        else:
            # need to create this value
            if surplus > 0:
                surplus -= 1
                cost += A
            else:
                cost += B

        best = min(best, cost)

    print(best)

if __name__ == "__main__":
    solve()
```该实现首先构建一个频率表，以便我们可以查询平均时间为 O(1) 的时间内每个怪异数存在多少个副本。 然后它迭代可能的前缀长度 K。 

在每一步中，如果该值已经存在，则免费使用一份副本，其余的则作为剩余存储，因为它们可以在以后进行转换。 如果该值不存在，我们必须通过使用剩余卡并将其转换（成本 A）或购买新卡（成本 B）来支付。 我们总是更喜欢在可用时使用剩余资金，因为它可以避免产生额外的外部购买。 

变量`best`跟踪所有前缀的最小成本。 这是必要的，因为进一步扩展 K 总是会增加成本，因此最佳 K 被发现为前缀级数的最小值。

 ## 边缘情况

 当重复创造盈余但交易成本高昂时，就会出现一个微妙的情况。 例如，如果 A 很大，仍然应该产生盈余，但永远不会使用，因为购买总是更便宜。 该算法自然地处理了这个问题，因为只有在有益的时候才会消耗剩余的资金； 否则我们直接购买。 

另一个边缘情况是没有出现像 1 或 2 这样的早期数字。该算法正确地强制购买这些前缀并单调累积成本，确保不可能提前跳过 K，因为 K 总是按顺序构建并在每一步进行评估。 

最后，当所有数字都从 1 开始连续时，大前缀的成本保持为零，直到我们超过现有的最大值，此时开始购买或转换。 前缀最小值正确捕获了最佳停止点。
