 ## 解决方案
 ## 问题理解

 我们得到了三堆筹码。 在每一回合中，玩家可以从一堆筹码中获取筹码，选择不超过该堆大小的任何正数，或者执行全局移动，同时从所有三堆筹码中获取相同的正数，但仅限于最小的筹码堆大小。 

玩家交替移动，而圣光总是开始。 拿到最后筹码的玩家获胜，这意味着所有筹码都变为零的位置是刚刚移动的玩家的获胜最终状态。 

所以问题是一个小三元组状态空间上的两人完美信息博弈$(a,b,c)$，我们需要判断起始玩家是否强制获胜。 

约束条件非常小，每个桩的大小最多为 50。这立即告诉我们，完整的状态空间最多包含$51^3 = 132651$状态，它足够小，可以使用动态编程或记忆递归进行完整的游戏图搜索。 

不明显的困难是第二种类型的动作。 玩家可以将所有三个堆减少相同的数量，这会将堆耦合起来并防止简单分解为独立的 Nim 堆。 

一些边缘情况说明了结构：

 如果所有堆都为零，则当前玩家没有动作，因此答案是失败，如输入所示`0 0 0`。 

如果只有一堆非零，比如说`0 0 1`，玩家可以立即拿下最后一个筹码并获胜。 

一个更微妙的情况是`1 2 3`。 直觉可能会建议采取多种行动，但最佳玩法会导致第一个玩家处于失败位置，如示例所示。 

诸如“总是从最大的一堆中获取”之类的天真贪婪的想法会失败，因为全局移动可能会以无效局部推理的方式重塑状态。 

## 方法

 解决问题的一个直接方法是将其视为一个博弈图，其中每个状态$(a,b,c)$是一个节点，每个有效的移动都会转移到另一个节点。 如果至少有一个移动导致失败，则该位置为获胜；如果每一步移动都导致获胜，则为失败。 

这建议使用记忆化的递归定义。 来自一个州$(a,b,c)$，我们尝试所有单桩缩减和所有有效的全局缩减，并递归地评估结果状态。 由于每堆最多 50 个，因此状态总数是有界的，每个状态最多分支为$O(50 + 50)$转换，总共最多提供几百万个转换。 这已经够快了。 

然而，有一种更清晰的结构观察，消除了繁重搜索的需要。 全局移动有效地平等地减少了所有桩，这意味着在许多转换中只有桩之间的相对差异很重要。 这表明该游戏的行为类似于受约束的公正游戏，其中对称性和小边界使得完整的 DP 足以无需优化。 

因此，我们选择对所有状态进行记忆化 DFS。

 | --- | --- | --- | --- |
 | 无备忘录的蛮力递归 | 指数| O(1) | O(1) | 太慢了|

 ## 算法演练

 我们定义一个函数`win(a, b, c)`返回当前玩家是否可以从该状态强制获胜。 

1.通过排序对状态进行归一化$(a,b,c)$以便等效的配置映射到相同的状态。 这减少了由堆排列引起的冗余计算。 
2. 如果所有牌堆都为零，则返回失败。 没有可用的动作，因此当前玩家无法获胜。 
3. 对于每一堆，尝试移除$k$芯片在哪里$1 \le k \le$桩尺寸。 采取行动后，递归检查最终的位置是否对对手不利。 如果存在任何此类移动，则将当前状态标记为获胜。 
4. 计算最小桩值$m = \min(a,b,c)$。 对于每个$k$从 1 到$m$, 模拟去除$k$同时从所有三堆筹码中取出筹码，并再次检查结果状态是否正在丢失。 如果任何此类举动导致失败，请将当前状态标记为获胜。 
5. 如果所有可能的动作都不会导致失败，则将当前状态标记为失败。 

我们记住每个三元组的结果，以确保每个状态仅计算一次。 

### 为什么它有效

 每个状态都根据有限非循环游戏图中的最佳玩法进行分类（因为每次移动都会严格减少筹码的总和）。 递归探索所有合法的移动，并且获胜条件符合标准的极小极大规则：当且仅当一个状态至少有一次到失败状态的转换时，该状态才获胜。 记忆化保证了共享子问题的一致性，并且保证了终止，因为每一步都会减少芯片总数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

from functools import lru_cache

@lru_cache(None)
def win(a, b, c):
    a, b, c = sorted((a, b, c))
    if a == b == c == 0:
        return False

    # single pile moves
    piles = [a, b, c]
    for i in range(3):
        for take in range(1, piles[i] + 1):
            nxt = list(piles)
            nxt[i] -= take
            nxt.sort()
            if not win(nxt[0], nxt[1], nxt[2]):
                return True

    # global moves
    m = min(a, b, c)
    for take in range(1, m + 1):
        nxt = [a - take, b - take, c - take]
        nxt.sort()
        if not win(nxt[0], nxt[1], nxt[2]):
            return True

    return False

def main():
    a, b, c = map(int, input().split())
    print("Yes" if win(a, b, c) else "No")

if __name__ == "__main__":
    main()
```实现的核心是memoized`win`功能。 对每个状态进行排序可确保排列如下`(1,2,3)`和`(3,2,1)`受到相同的对待，防止对称分支的冗余探索。 递归尝试所有合法的移动，首先以所有可能的方式减少单个堆，然后应用同时减少移动。 

基本情况处理空状态。 记忆缓存至关重要，因为如果没有它，相同的子游戏将在不同的移动序列中多次重新计算。 

## 工作示例

 ### 示例 1：`0 0 1`| 状态| 移动类型 | 结果状态 | 赢了？ |
 | --- | --- | --- | --- |
 | (0,0,1) | (0,0,1) | 从第三堆取 1 | (0,0,0) | (0,0,0) | 失去|

 唯一可用的移动直接导致最终状态。 由于该状态对于下一个玩家来说是失败的，因此当前状态是获胜的。 

这证实了任何拥有单筹码的仓位都会立即获胜的规则。 

### 示例 2：`1 2 3`| 状态| 移动类型 | 结果状态 | 对手结果 |
 | --- | --- | --- | --- |
 | (1,2,3) | (1,2,3) | 各种单招| 多个州 | 全部为对手获胜|
 | (1,2,3) | (1,2,3) | 全球减少1 | (0,1,2) | (0,1,2) | 为对手获胜|
 | (1,2,3) | (1,2,3) | 全球减少2 | (0,0,1) | (0,0,1) | 为对手获胜 |

 每一个可用的动作都会转变为对手仍然有获胜策略的状态。 因此，原来的状态正在消失。 

这表明，尽管存在简化棋盘的走法，但它们都不会为对手带来失败的局面。

 ## 边缘情况

 全零状态`0 0 0`直接作为基本案例处理。 由于不存在任何移动，该函数立即返回失败，与前一个玩家已经拿走最后一个筹码的事实相匹配。 

单非零桩情况如`0 0 1`成为获胜，因为单堆移除的循环包括恰好拿走一个筹码，直接转换到最终失败状态。 

高度对称的情况，例如`2 2 2`通过排序自动标准化，因此所有排列都会崩溃为一种记忆状态。 该算法评估所有全局归约，并发现至少一个动作会导致对手失败，从而确保正确分类，而无需多余的探索。
