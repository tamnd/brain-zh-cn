 ## 解决方案
 ## 问题理解

 给定一个二进制字符串，其中 0 和 1 出现的数量相等，且长度为偶数。 目标配置不是任意的：我们希望字符串完全交替，这意味着每个相邻的字符对必须不同。 由于字符串是平衡的，因此只有两种可能的最终形式：一种以 0 开头，一种以 1 开头。 

唯一允许的操作是反转任何连续的子字符串。 反转可以完全重新排序该段内的元素，同时保持字符串的其余部分不变。 任务是找到将初始字符串转换为任何有效的交替字符串所需的最少反转次数。 

测试用例总长度的限制最多为 10^5。 这立即排除了任何尝试所有子字符串或逐步模拟转换的解决方案。 每个测试用例的任何比线性或近线性更糟糕的东西都会很困难，因此解决方案必须提取字符串的结构属性而不是模拟操作。 

一个微妙的一点是，反转是极其强大的操作。 天真的直觉可能表明需要许多操作，因为反转是局部的，但实际上，如果选择正确，单个反转可以修复多个放错位置的字符。 困难不在于执行操作，而在于确定有多少操作是根本必要的。 

一个经常误导天真的贪婪想法的边缘情况是，字符串已经交替，但与假设的目标相比，以“错误”的第一个字符开头。 例如，如果我们假设目标是 0101...，但最优值是 1010...，那么天真的逐个位置校正策略可能会过度计算工作量。 

当不匹配聚集时会出现另一种失败情况。 例如，在像 111000 这样的字符串中，幼稚的策略可能会尝试单独修复每个不匹配，而单个精心选择的反转可以同时修复多个位置。 这是暴力本地修复失败的核心原因。 

## 方法

 暴力方法会在每一步尝试反转所有可能的子串，并对所有可达的字符串运行 BFS，直到找到替代配置。 每个状态都有 O(n^2) 次转换，并且状态数量呈指数级增长，因此即使 n 约为 20，这也很快变得不可行。正确性很简单，因为 BFS 探索了所有可能性，但状态空间立即爆炸。 

为了改进，我们将视角从构建操作转向测量相对于交替目标的混乱。 修复一个目标模式，例如 0101…我们可以将输入字符串与该目标进行比较并标记不匹配的位置。 这些不匹配是唯一重要的地方，因为正确的位置已经满足了局部的最终目标。 

关键的见解是，逆转可以在一次移动中纠正最多两次“运行”的不匹配。 这里的运行意味着字符串与目标模式不一致的连续段。 在这样的片段内，反转可以翻转结构，从而使多个不正确的对齐同时崩溃。 最优解的结构简化为将这些不匹配段配对。 

一旦我们针对两个可能的交替目标计算不匹配位置，答案就变成消除所有不匹配所需的最少操作数。 事实证明，这只是更好目标的不匹配段数量的一半，因为每个操作都可以合并或修复两个边界转换。 

因此，我们不是模拟逆转，而是将问题简化为在与每个目标进行比较时计算正确位置和错误位置之间的转换。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 字符串上的强力 BFS | O(2^n · n^2) | O(2^n · n^2) | O(2^n·n) | O(2^n·n) | 太慢了 |
 | 不匹配段计数 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们评估两个候选目标：交替从 0 开始和交替从 1 开始。 

对于每个目标，我们扫描字符串并将每个索引相对于该目标模式分类为正确或不正确。 

1. 通过检查索引的奇偶性来隐式构建预期的交替模式。 如果索引 i 为偶数，则一个目标的预期值为 0，另一个目标的预期值为 1。 
2. 遍历字符串，标记s[i]与预期不同的位置。 
3. 计算由不匹配位置组成的连续段的数量。 每次我们从匹配区域进入不匹配区域时，我们都会增加段计数。 
4. 对于该目标，所需的操作数量等于不匹配段数量的一半，向上舍入。 
5. 对另一个目标重复此操作，并取两个结果中的最小值。 

除以二背后的直觉来自反转的行为方式：一次反转可以通过翻转两个单独的不匹配块之间的段来连接和解决它们，从而有效地合并校正工作。 

### 为什么它有效

 关键的不变量是唯一有意义的结构是相对于固定交替模式的正确位置和不正确位置之间的边界。 在不匹配段内，所有位置都同样“在上下文中错误”，并且可以选择反转以通过翻转奇偶校验对齐来消除或合并段。 由于每个操作最多可以消除两个不匹配边界，因此答案取决于存在多少个这样的边界，这可以通过计算连续的不匹配块来精确捕获。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        def calc(start_bit):
            mismatches = []
            for i, ch in enumerate(s):
                expected = '1' if (i % 2) ^ start_bit else '0'
                mismatches.append(ch != expected)

            segments = 0
            i = 0
            while i < n:
                if not mismatches[i]:
                    i += 1
                    continue
                segments += 1
                while i < n and mismatches[i]:
                    i += 1

            return (segments + 1) // 2

        ans0 = calc(0)
        ans1 = calc(1)
        print(min(ans0, ans1))

if __name__ == "__main__":
    solve()
```该解决方案首先定义一个辅助函数，该函数评估如果我们强制交替模式以特定位开始则需要多少次操作。 不匹配数组隔离了所有违反此目标的位置。 然后我们将这些不匹配压缩成连续的块，因为块的内部结构对于反转并不重要，只关心存在多少个单独的块。 

最终公式`(segments + 1) // 2`捕捉到这样一个事实：在最好的情况下，每次反转可以处理两个不匹配的块，而剩余的单个块需要一次操作。 

主循环评估两个可能的交替目标并选择更好的一个。

 ## 边缘情况

 完全交替的字符串，例如`10101010`为正确的目标生成零个不匹配段，因此段计数为零，并且答案立即变为零。 该算法正确地避免了不必要的操作，因为不存在不匹配边界。 

像这样的字符串`0011`与任一交替模式相比，仅创建一个不匹配片段。 公式`(1 + 1) // 2`给出 1，符合直觉，即一次反转足以修复单个连续的错误区域。 

更加碎片化的字符串，例如`110010`产生多个不匹配片段。 该算法对它们进行精确分组，并将分段数量转换为操作，确保隔离的不正确区域得到最佳配对。
