 ## 解决方案
 ## 问题理解

 我们得到了一系列菜肴，每道菜都与从烤箱中取出的“理想”时间相关。 这个问题中的时间是离散的，并且每次增加一分钟。 每分钟，我们最多可以取出一个盘子，并且每个盘子最终必须恰好被取出一次。 如果一道菜的首选时间是$t_i$被及时取出$T$，我们支付等于绝对差值的罚金$|T - t_i|$。 目标是安排移除时间，这正是整数$1, 2, \dots, n$，这样每道菜都被分配了一个唯一的时间，并且总的惩罚被最小化。 

换句话说，我们将每道菜与长度排列中的不同时间段相匹配$n$，成本是与首选位置的绝对偏差之和。 

约束很小：所有测试用例中的盘子总数最多为 200 个。这立即告诉我们，每个测试用例具有二次甚至三次行为的解决方案是可以接受的，而任何指数超过排列的解决方案则不可接受。 单纯的阶乘枚举是不可能的，因为即使$20!$已经太大了，但是对子集或过度排序位置进行动态规划是可行的。 

当多个菜肴共享相同的首选时间时，就会出现一个微妙的问题。 像“总是按照输入顺序为每道菜分配最接近的可用时间”这样的贪婪分配可能会失败，因为早期的决策会阻碍更好的全局配对。 该结构本质上是全局的：选择一道菜的时间会改变所有其他菜的可用时间段。 

天真的贪婪的一个小失败说明可以随着时间的推移而构建$[1, 1, 100, 100]$。 如果我们贪婪地首先将 1 分配给时间 1 和 2，我们会立即将 100 推得远远的，这是不必要的。 相反，全局最优安排会对称地分配分配。 

## 方法

 核心困难在于我们正在匹配两个有序结构：具有值的菜肴$t_i$，和时段$1 \dots n$。 一旦我们对两者进行排序，问题就开始类似于线度量上的分配问题。 

一个蛮力的想法是尝试将菜肴分配给时间段的每一种排列并计算成本。 这是正确的，因为每个有效的时间表都是时间的排列。 然而，排列的数量是$n!$，即使对于$n = 20$。 每次评估费用$O(n)$，因此总数变为$O(n \cdot n!)$，立即爆炸。 

关键的观察是一条线上的绝对差异成本具有很强的排序特性。 如果两道菜有偏好时间$a \le b$但被分配到时间$x \le y$，交换分配永远不会增加成本。 这是经典的交换论证，意味着存在两个序列一致排序的最佳解决方案。 

所以我们对首选时间数组进行排序。 现在任务变成了配对$i$-最小的菜$i$-th 时隙以最小化总绝对偏差的方式。 然而，我们并不被迫分配给$1..n$直接按顺序； 我们正在选择位置，最佳 DP 会跟踪我们在时间上取得的进展。 

一个干净的公式是对排序菜肴的索引和当前时间进行动态编程。 由于时间严格增加且受以下限制$n$，我们定义一个 DP，我们按照时间递增的顺序放置菜肴。 在步骤$i$，我们选择一个时间$t$大于以前，并支付$|t - a_i|$。 这成为具有单调转换的线上的标准 DP，可解为$O(n^2)$。 

我们计算：$$dp[i][j] = \text{minimum cost to assign first } i \text{ dishes ending at time } j$$与之前所有时间的过渡$k < j$：$$dp[i][j] = \min_{k < j}(dp[i-1][k]) + |j - a_i|$$我们可以优化前缀最小值以避免额外的因素。

 ## 算法演练

 1. 对首选烹饪时间数组进行排序。 这将问题减少到匹配有序位置，由于绝对距离的交换参数，这是有效的。 
2.定义一个DP表，我们按照排序顺序一一处理菜肴。 在每一步中，我们都会决定当前盘子被移除的时间。 
3. 维护一个从 1 到 1 的时隙索引$n$。 我们确保时间严格增加，因为每个时段只能使用一次。 
4. 每道菜$i$，计算在每个可能的时间放置它的成本$j$，即$|j - a_i|$，并将其与之前的最佳放置相结合。 
5. 使用前一个 DP 行的前缀最小值来计算中的转换$O(1)$每个状态，而不是扫描以前的所有时间。 这将复杂性从三次降低到二次。 
6. 答案是最后 DP 行中所有有效结束时间的最小值。 

### 为什么它有效

 关键的不变量是在处理第一个之后$i$菜肴，每个 DP 状态代表所有有效分配中的最小可能成本，其中$i$菜肴被分配到严格增加的时间段。 排序约束确保不重新分配可以在不破坏可行性的情况下局部提高成本。 由于绝对差值成本在一条直线上是凸的，因此最优结构在排序后遵循单调匹配，因此将 DP 限制为增加时间索引不会丢弃任何最优解。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()

        INF = 10**18

        # dp[j]: min cost after placing current i items, ending at time j
        dp = [INF] * (n + 1)

        # initialize: place first dish at any time
        for j in range(1, n + 1):
            dp[j] = abs(j - a[0])

        for i in range(1, n):
            new_dp = [INF] * (n + 1)

            prefix_min = INF
            for j in range(1, n + 1):
                prefix_min = min(prefix_min, dp[j-1])
                new_dp[j] = prefix_min + abs(j - a[i])

            dp = new_dp

        print(min(dp[1:]))

def main():

    for _ in range(q):

        INF = 10**18

        for j in range(1, n + 1):
            dp[j] = abs(j - a[0])

            prefix_min = INF

                prefix_min = min(prefix_min, dp[j-1])
                new_dp[j] = prefix_min + abs(j - a[i])

    main()
```实现首先对首选时间进行排序，这强制了 DP 参数所需的单调结构。 DP 数组表示分配菜肴前缀后的最佳成本，在特定时间段结束。 

该转换使用之前状态的滚动前缀最小值。 表达式`prefix_min = min(prefix_min, dp[j-1])`捕获严格在时间之前结束先前作业的最佳方式`j`，它强制时隙的唯一性。 这避免了之前所有时间的显式内部循环。 

最终答案是所有可能的最后一次位置的最小值，因为最后一道菜可以在任何地方结束。 

一个微妙的实现细节是基于 1 的时隙索引。 这与问题陈述相匹配，并避免计算绝对差时出现相差一的错误。

 ## 边缘情况

 对于相同的首选时间，例如$[x, x, x]$，DP 自然地将分配分配到连续的时隙中。 每增加一个盘子至少会产生一个单位的位移，因为只有一个盘子可以占据精确的最佳时间，其余的必须向外移动。 前缀最小转换确保算法在不违反顺序的情况下逐渐考虑较晚的时间位置。 

对于严格增加或减少的序列，排序使它们相同，并且DP减少到匹配索引$i$到时间$i$，当值已经与其位置匹配时，产生零成本。
