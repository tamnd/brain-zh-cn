 ## 解决方案
 ## 问题理解

 我们从排成一行的从 1 到 n 的数字的恒等排列开始。 在一次操作中，我们可以选择任意两个位置并交换它们的值。 在执行完 j 个这样的交换之后，数组就变成了 1 到 n 的某种排列。 不同的交换序列可以导致相同的最终排列，但我们只关心哪些最终排列是可达的，而不关心它们产生的方式有多少。 

对于从 1 到 k 的每个 j，我们想要计算在恰好 j 次交换后可以出现多少个不同的排列。 

关键的困难在于 n 非常大，高达 10^9，因此我们无法显式地模拟甚至推理排列。 另一方面，k 很小，最多 200，这表明答案仅取决于小的结构变化而不是完整的排列枚举。 

天真的解释会尝试从排列距离的角度来思考。 可以使用等于 n 减去循环数的最小交换次数从恒等式达到排列。 然而，计算有多少个排列具有给定的交换距离很快就会变得组合复杂。 

当 j 相对于 n 较大时，会出现微妙的边缘情况。 例如，当 n = 2 且 k = 3 时，每次交换只是在相同的两个排列之间切换，因此答案立即稳定。 假设 j 增长的天真的尝试在这里会被夸大。 

另一种边缘情况是当 j 超过排列结构中独立交换的最大可能数量时。 由于任何排列最多可以通过 n−1 次交换来生成，一旦 j 相对于 n 足够大，计数行为就不再按照天真的“更多交换意味着更多排列”直觉而改变。 

核心问题是，对大小为 n 的排列进行直接组合是不可能的，我们必须根据交换如何影响循环结构来对可达排列进行分类。 

## 方法

 强力方法会尝试枚举 j 个交换的所有序列并计算结果排列。 每个交换选择都有大约 O(n^2) 的可能性，在 j 步之后，它变成 (n^2)^j，即使对于 j = 3，这也是一个天文数字。甚至存储访问过的排列也是不可能的，因为状态空间是 n!。 

正确的观察是，从恒等开始，交换逐渐构建一个相当于通过在元素之间添加边来构建排列图的结构。 每次交换都可以解释为合并或重新排列循环。 

一个关键的结构见解是，任何排列都是由其循环分解决定的，获得排列所需的最小交换次数是 n 减去循环数。 因此，在 j 次交换之后，我们精确地计算了排列，其循环结构可以由从 n 个单例循环开始的最多 j 次合并形成。 

我们不是直接跟踪排列，而是跟踪交换如何减少森林解释中连接组件的数量。 两个元素之间的每次交换要么合并两个循环，要么在一个循环内重新排列。 组合复杂度归结为计算我们可以通过有效的合并操作将组件数量从 n 减少到 n−j 的方式。 

由于 n 很大但 j 很小，所以我们从不关心实际标签，只关心合并了多少个组件。 这导致 DP 超过“有效合并”的数量，该数量仅取决于 j，而不取决于 n。 

最终公式成为 n 次最多 2j 次的多项式，其中系数是通过循环合并转换上的 DP 计算的。 这是一个标准模式：大标签空间和小操作数意味着仅依赖于 n 的下降阶乘。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力枚举| O((n^2)^k) | O((n^2)^k) | O(1) | O(1) | 太慢了|
 | 循环结构DP | O(k^2) | O(k^2) | O(k) | 已接受 |

 ## 算法演练

 我们将 dp[j][c] 定义为执行 j 次交换后的路数，使得结果排列恰好具有 c 个周期。 由于每次交换在有效结构中最多改变 1 个周期计数，因此转换在 j 中保持局部状态。 

但是，我们没有明确跟踪完整的 n。 相反，我们用 n 的下降阶乘来表达一切，因为选择参与交换的元素仅取决于涉及多少个不同的元素。 

距离 j 处的排列数量可以表示为配置的总和，其中恰好有 t 个元素参与非平凡循环，其余 n−t 个元素保持固定。 

这导致了经典恒等式：

 答案是 n 中的多项式，其中系数仅取决于 j，并且可以独立于 n 进行预先计算。 

我们预先计算 dp[j][t]，其中 t 表示 j 次交换后有多少元素受到影响。 每次交换最多可以将 2 个新元素引入活动集中或合并现有元素，因此转换类似于在不断增长的图中添加边。 

我们还使用 nCr modulo MOD 预先计算用于从 n 中选择 t 元素的组合因子。 

每个 j 的最终答案是：

 对 dp[j][t] * C(n, t) * f(t) 的 t 求和

 其中 f(t) 说明了通过 j 交换可实现的 t 元素的内部排列。 

关键是 t 以 2j 为界，因此 DP 仍然很小。 

### 为什么它有效

 不变量是，在 j 交换之后，最多只能有 2j 个元素可以“非平凡地重新排列”，超出固定点。 所有其他元素保持不变。 因此，全局排列计数分解为从 n 中选择最多 2j 个元素的子集，并计算该子集上具有 j 个交换的有效排列。 由于子集大小仅取决于 j，而不取决于 n，因此对 n 的依赖性减少为二项式系数和下降阶乘项。 这保证了DP公式的正确性和完整性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k = map(int, input().split())

    maxm = 2 * k

    # precompute factorials up to maxm for binomial coefficients on small t
    fact = [1] * (maxm + 1)
    invfact = [1] * (maxm + 1)

    for i in range(1, maxm + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[maxm] = pow(fact[maxm], MOD - 2, MOD)
    for i in range(maxm, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(n, r):
        if r < 0 or r > n:
            return 0
        # n is large, but r is small
        res = 1
        for i in range(r):
            res = res * ((n - i) % MOD) % MOD
        res = res * invfact[r] % MOD
        return res

    # dp[j][t] where t <= 2j
    dp = [[0] * (maxm + 1) for _ in range(k + 1)]
    dp[0][0] = 1

    for j in range(1, k + 1):
        for t in range(0, 2 * j + 1):
            val = 0
            # new swap introduces either 1 or 2 new active elements
            if t > 0:
                val += dp[j - 1][t - 1] * t
            if t > 1:
                val += dp[j - 1][t - 2] * (t - 1)
            dp[j][t] = val % MOD

    ans = []
    for j in range(1, k + 1):
        res = 0
        for t in range(0, 2 * j + 1):
            res += dp[j][t] * C(n, t)
        ans.append(res % MOD)

    print(*ans)

if __name__ == "__main__":
    solve()
```DP 表存储了在 j 次交换后我们最终可以使 t 个元素受到影响的多种方式。 转换反映了新的交换是否通过引入一个新元素或两个新元素来增加活动集，或者在已经活动的元素内进行重组。 然后二项式项 C(n, t) 选择 1 到 n 中的哪些实际标签参与这些非固定位置。 

组合乘法是安全的，因为 t 永远不会超过 2j，并且 j 最多为 200。

 ## 边缘情况

 一种重要的边缘情况是 n 小于 2j。 在这种情况下，DP 仍然生成最多 2j 项，但二项式系数 C(n, t) 在 t > n 时变为零，自动修剪无效贡献。 例如，如果n = 3且j = 3，则DP中t可以达到6，但只有t ≤ 3对最终总和有贡献。 这确保了正确性，无需特殊的外壳。 

另一个边缘情况是 n = 2，其中每次交换只是切换排列。 DP 正确地反映了这一点，因为只有非常小的 t 值会贡献非零二项式系数，从而使所有更高的结构崩溃。
