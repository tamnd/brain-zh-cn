 ## 解决方案
 ## 问题理解

 我们得到一个数组，并允许通过获取两个相邻元素、删除它们并用它们的 XOR 替换它们来重复压缩它。 每个操作都会将长度减少一，但保留了强大的结构属性：整个数组的 XOR 保持不变，因为用 XOR 替换两个值不会影响所有元素的总 XOR。 

该过程一直持续到我们决定停止为止，但我们不允许将数组减少到两个元素以下。 目标是确定是否有可能达到所有剩余元素都相等的状态。 

的约束条件为$n \le 2000$表明二次或偶数$O(n^2 \log n)$解决方案可能会顺利通过，但任何立方体在多个测试用例中都会存在风险。 然而，这里的关键在于，问题不在于模拟操作，而在于识别表征目标配置何时可达的结构不变量。 

天真的思维的一个常见失败案例是假设我们可以贪婪地合并以实现平等。 例如，在像这样的数组中$[1, 2, 3]$，不同的合并顺序会导致不同的中间数组，并且贪婪的尝试可能会错误地得出不可能的结论，因为它会过早陷入困境，即使不同的序列有效。 另一个微妙的陷阱是假设如果数组已经具有相等的元素，则答案始终为“是”。 当均衡需要减少两个元素以下时，这种方法就会失败，而这是被禁止的。 

第三种边缘情况是小数组。 为了$n = 2$，根本不允许任何操作，所以答案只是两个元素是否已经相等。 

## 方法

 暴力方法试图模拟相邻异或合并的每个可能的序列。 每个步骤选择一对，分支到一个新数组，并继续，直到所有元素都相等或只剩下两个。 可能的合并序列的数量是巨大的，本质上相当于对一个大小的数组上的所有二叉合并树进行计数$n$，它像加泰罗尼亚语一样增长并呈指数增长。 即使是为了$n = 30$，这已经变得不可行了。 

关键的观察结果是，相邻的 XOR 合并不会改变数组的全局 XOR，更重要的是，合并形成的任何段都对应于将数组划分为连续的组，这些组的 XOR 成为最终元素。 所以最终状态相当于选择数组的一个分区为$k \ge 2$连续的段，其中每个段具有相同的 XOR 值。 

如果每个段的最终值为$x$，然后对所有段进行异或运算得出总异或等于$x$如果$k$是奇数，并且$0$如果$k$是均匀的。 这就引出了中心条件：我们必须检查是否可以将数组拆分为至少两个连续的部分，且其 XOR 全部相等。 

唯一有意义的候选人$x$来自前缀结构。 如果总异或为零，我们可以瞄准异或零的多个段。 否则，我们需要一种方法来分割成至少三个段，全部等于总异或，如果我们能找到产生所需结构的两个分割点，那么这就是可能的。

 ## 算法演练

 我们将问题简化为有关前缀异或的推理。 

1. 计算数组的总异或。 该值确定任何有效分区中每个最终段必须相等的值。 
2. 如果总异或为零，我们检查数组是否可以分成至少两个连续的段，每个段的异或为零。 我们从左到右扫描，保持运行中的异或，并计算在结束之前它变为零的次数。 如果我们能找到至少两个这样的分割，那么我们就可以形成至少两个相等的线段，答案是“是”。 
3. 如果总 XOR 不为零，则任何有效的最终配置必须至少包含三个段，每个段的 XOR 等于总 XOR。 这是因为两个段将异或回零，与非零总数相矛盾。 因此，我们寻找两个不同的切割点，其中前缀 XOR 等于总 XOR，并且在第二次切割之后，剩余的后缀也必须匹配相同的 XOR 结构。 这相当于找到至少两个有效的前缀位置并确保有第三个段的空间。 
4. 我们扫描数组，跟踪前缀异或，并记录等于目标值的位置。 如果我们可以在数组末尾之前找到至少两个这样的位置，我们可以通过确保第二次切割不在最后一个元素来检查隐式形成第三段的可行性。 

### 为什么它有效

 XOR 运算是关联和可交换的，因此任何相邻合并序列都相当于将数组划分为连续的块，其中每个块都折叠为其 XOR。 因此，最终的数组完全由这样的划分决定。 所有最终元素都相等的条件成为段 XOR 相等性的约束。 由于只有前缀 XOR 值才能定义有效的段边界，因此问题简化为计算可行的前缀匹配。 这消除了对合并顺序的任何依赖并保证了正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        total = 0
        for x in a:
            total ^= x

        if n == 2:
            print("YES" if a[0] == a[1] else "NO")
            continue

        # If total XOR is zero, we just need at least two zero-prefix splits
        if total == 0:
            cur = 0
            cuts = 0
            for i in range(n - 1):
                cur ^= a[i]
                if cur == 0:
                    cuts += 1
            print("YES" if cuts >= 2 else "NO")
        else:
            cur = 0
            cuts = 0
            for i in range(n - 1):
                cur ^= a[i]
                if cur == total:
                    cuts += 1
            print("YES" if cuts >= 2 else "NO")

if __name__ == "__main__":
    solve()
```该解决方案首先计算整个数组的异或，这确定了有效分解中每个段的唯一可能的候选值。 特殊情况$n = 2$直接处理，因为无法进行任何操作。 

对于较大的数组，逻辑根据总异或是否为零分为两种结构情况。 在这两种情况下，实现都依赖于扫描前缀异或并计算所需值在最终索引之前出现的频率，确保我们始终为至少两个段留出空间。 

一个常见的陷阱是忘记将剪切限制在最后一个元素之前的位置。 允许在末尾进行剪切会错误地计算最后一段为空的无效分区。

 ## 边缘情况

 对于$n = 2$，算法直接比较两个值，因为不允许合并。 这可以防止错误地假设进一步的变换可以使它们相等。 

对于总 XOR 为零但仅存在一个有效前缀切割的数组，算法会正确拒绝它们。 一个具体的案例是$[1, 2, 3]$，其中总异或为零，但在最后一个元素之前只有一个前缀达到零，从而防止出现第二段。 

对于非零总 XOR 情况，需要至少两个有效的前缀匹配可确保我们可以形成至少三个段，这是避免崩溃回不一致的 XOR 约束所需的最小值。
