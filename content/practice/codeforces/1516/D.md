 ## 解决方案
 ## 问题理解

 我们得到了一个数组，最多可达$10^5$整数。 对于每个查询$[l,r]$，我们必须将该子数组拆分为尽可能少的连续部分，以便在每个部分内，所有元素的乘积等于这些元素的最小公倍数。 

任务不是构建分区。 我们只需要最少数量的段。 

关键的难点在于，最多有$10^5$查询，因此独立回答每个查询是不可能的。 我们需要大量的预处理和非常快速的查询处理。 

要理解该条件，请考虑包含数字的段$x_1,x_2,\dots,x_k$。 

仅当线段的多个元素中均未出现质因数时，乘积才等于 LCM。 

例如，该段$[6,35]$是有效的。 质因数分解是：$$6 = 2 \cdot 3,\qquad 35 = 5 \cdot 7$$每个素数总体上只出现一次，所以：$$6 \cdot 35 = \operatorname{lcm}(6,35)$$现在考虑$[6,10]$：$$6 = 2 \cdot 3,\qquad 10 = 2 \cdot 5$$主要的$2$出现在两个数字中。 该产品是$60$，而 LCM 是$30$。 该段无效。 

这一观察彻底改变了问题。 当且仅当没有质因数出现在该线段内的两个不同位置时，该线段才是有效的。 

这些约束迫使我们采取有效的解决方案。 和$n,q \le 10^5$， 甚至$O(nq)$大约需要$10^{10}$运营。 查询处理必须围绕$O(\log n)$，这强烈建议预处理、二进制提升或相关技术。 

一些边缘情况很容易被错误处理。 

考虑：```
1
6
```单个元素始终有效，因为其乘积等于其 LCM。 答案一定是1。 

考虑：```
2 4
```两个数字都包含质因数 2。整个段无效，因此必须将其分成两段：```
[2] [4]
```答案是 2。粗心的实现仅检查相邻数字是否互质会错误地接受整个段。 

考虑：```
6 10 15
```每对都共享一个素数因子，但没有素数同时出现在所有三个位置上。 最大有效范围仍必须仔细计算。 不跟踪全局主要事件的贪婪局部决策可能会失败。 

另一个微妙的情况是值 1。它没有素因数，也不会产生冲突。```
1 1 1 1
```整个段都是有效的，答案是 1。任何假设每个数字都贡献素因数的实现都会错误地缩短范围。 

## 方法

 暴力解决方案将独立处理每个查询。 

对于查询$[l,r]$，我们可以尝试扩展一个线段，同时保留已使用的素因子集。 一旦出现重复的素数，我们就剪切并开始一个新的片段。 这种贪婪的构造实际上是最优的，因为尽可能扩展有效段永远不会增加片段的数量。 

问题在于复杂性。 单个查询可以检查$O(n)$职位。 和$10^5$查询，最坏的情况变成$O(nq)$， 大致$10^{10}$运营。 

关键的观察是，有效性仅取决于重复的素因子。 

假设我们知道，对于每个起始位置$i$，最远位置$R[i]$这样$[i,R[i]]$是有效的。 那么任何查询的最佳分区都很简单：

 从当前位置开始，始终取最长的有效段。 这与跳跃区间完全相同的贪心策略。 

剩下的挑战就是回答：

 > 起始位置$l$，需要多少次贪婪跳跃才能到达或通过$r$？ 

这是一个经典的二元提升问题。 

我们首先使用滑动窗口计算每个最大有效间隔。 然后我们在其中构建跳转指针：$$up[0][i] = R[i] + 1$$意思是“在从$i$，下一段从这里开始”。

 通常会构建更高的功率：$$up[k][i] = up[k-1][up[k-1][i]]$$然后，查询就变得与在停留在之前的同时重复向前跳转相同$r$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(nq)$|$O(n)$| 太慢了|
 | 最佳 |$O(n \log n + q \log n)$|$O(n \log n)$| 已接受 |

 ## 算法演练

 1. 计算每个数字的最小质因数$10^5$使用筛子。 
2. 对每个数组元素进行因式分解并存储其不同的质因数。 
3. 使用两指针窗口从每个位置开始构建最大有效间隔。 

维护当前窗口内每个质数的计数。 

延长右指针，同时质因数不会出现两次。 
4. 对于每个左端点$i$，存储最大有效右端点$R[i]$。 
5. 定义：$$up[0][i] = R[i] + 1$$如果最大段开始于$i$结束于$R[i]$，下一段必须开始于$R[i]+1$。 
6. 搭建二元升降台。 

对于每一个力量$k$,$$up[k][i] = up[k-1][up[k-1][i]]$$7. 回答询问$[l,r]$, 从位置开始$l$。 
8. 从最大到最小尝试幂。 

每当跳跃时$2^k$段仍然离开当前或之前的位置$r$，执行跳转并添加$2^k$到答案。 
9. 在所有可能的跳跃之后，需要最后一个段来覆盖剩余部分。 
10. 输出段总数。 

### 为什么它有效

 滑动窗口精确计算从每个位置开始的最大有效段，因为有效性条件是单调的。 一旦出现重复的质因数，再进一步扩展就永远无法恢复有效性。 

对于任何间隔，采用最长的有效前缀是最佳的。 任何较短的第一段都会留下更多未覆盖的元素，并且不能减少未来段的数量。 递归地重复这个论证证明了贪婪分区产生的碎片数量最少。 

跳转表存储该贪婪步骤的重复应用。 二进制提升只是加速了计算到达查询端点之前需要多少个贪婪段的过程。 由于贪心划分是最优的，所以统计出来的数字正是最小答案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MAXA = 100000
LOG = 18

# smallest prime factor
spf = list(range(MAXA + 1))
for i in range(2, int(MAXA ** 0.5) + 1):
    if spf[i] == i:
        step = i
        start = i * i
        for j in range(start, MAXA + 1, step):
            if spf[j] == j:
                spf[j] = i

n, q = map(int, input().split())
a = list(map(int, input().split()))

factors = [[] for _ in range(n)]

for i, x in enumerate(a):
    while x > 1:
        p = spf[x]
        factors[i].append(p)
        while x % p == 0:
            x //= p

cnt = [0] * (MAXA + 1)

R = [0] * n
r = 0

for l in range(n):
    while r < n:
        ok = True
        for p in factors[r]:
            if cnt[p]:
                ok = False
                break

        if not ok:
            break

        for p in factors[r]:
            cnt[p] += 1
        r += 1

    R[l] = r - 1

    for p in factors[l]:
        cnt[p] -= 1

up = [[n] * (n + 1) for _ in range(LOG)]

for i in range(n):
    nxt = R[i] + 1
    if nxt > n:
        nxt = n
    up[0][i] = nxt

up[0][n] = n

for k in range(1, LOG):
    prev = up[k - 1]
    cur = up[k]
    for i in range(n + 1):
        cur[i] = prev[prev[i]]

out = []

for _ in range(q):
    l, r = map(int, input().split())
    l -= 1
    r -= 1

    pos = l
    ans = 0

    for k in range(LOG - 1, -1, -1):
        nxt = up[k][pos]
        if nxt <= r:
            ans += 1 << k
            pos = nxt

    out.append(str(ans + 1))

print("\n".join(out))
```第一阶段计算每个值的最小素因子$10^5$。 这允许在对数时间内分解每个数组元素。 

每个位置仅存储不同的质因数。 同一数字内的重复幂是无关紧要的。 例如，$12 = 2^2 \cdot 3$仅贡献素数$2$和$3$。 

滑动窗口保持了每个素数在当前窗口内最多出现一次的不变量。 当添加下一个位置会引入重复素数时，扩展就会停止。 生成的右边界恰好是从当前左端点开始的最大有效线段。 

跳转表存储我们采取后到达的位置$2^k$贪婪的段。 位置$n$充当哨兵状态，防止越界访问。 

在查询处理过程中，循环贪婪地采取仍保留在查询范围内的最大可能跳转。 这是用于计数跳跃的标准二进制提升模式。 

一个常见的差一错误是忘记了$R[i]$包含在内，而下一段开始于$R[i]+1$。 另一个简单的错误是使用`< r`而不是`<= r`在提升条件下，当跳转恰好落在查询端点上时，它会低估。

 ## 边缘情况

 考虑：```
1 1
1
1 1
```数字 1 不贡献质因数。 滑动窗口立即扩展到整个元素，从而给出$R[1]=1$。 查询答案为1。 

考虑：```
2 1
2 4
1 2
```第一个位置贡献质数 2。当窗口尝试包含第二个位置时，质数 2 将出现两次。 扩张停止。 最大间隔变为$[1,1]$和$[2,2]$，产生答案 2。 

考虑：```
4 1
1 1 1 1
1 4
```没有位置贡献任何主要因素。 滑动窗口立即到达数组的末尾。 从第一个位置开始的最大间隔覆盖了整个查询，因此答案是 1。 

考虑：```
3 1
6 10 15
1 3
```位置 1 使用素数$\{2,3\}$。 位置2用途$\{2,5\}$，立即引发冲突。 第一个最大间隔在位置 1 结束。稍后会发生类似的冲突。 该算法正确地识别出多次切割是必要的，因为重复的素因子是在当前段内全局跟踪的，而不是仅在相邻元素之间跟踪的。
