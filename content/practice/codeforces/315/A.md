[CF 315A - Sereja 和瓶子](https://codeforces.com/problemset/problem/315/A)

 **标签：** 暴力破解
 **求解时间：** 1m 54s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 每个瓶子都有两个属性。 

价值`a[i]`是瓶子自己的品牌。 价值`b[i]`是这个瓶子可以打开的瓶子的品牌。 

如果存在其他瓶子的开启能力与其品牌相匹配，则可以打开该瓶子。 由于瓶子无论是已经打开还是仍然关闭都可以使用，因此我们只关心品牌之间的静态关系。 没有要模拟的操作序列。 

对于有品牌的瓶子`a[i]`，我们需要检查是否存在另一个瓶子`j`这样`b[j] = a[i]`。 如果存在这样的瓶子，瓶子`i`可以打开。 否则，永远无法打开。 

任务是计算有多少个瓶子不能被任何其他瓶子打开。 

限制非常小。 最多有100瓶。 即使是比较每对瓶子的算法也只能执行`100 × 100 = 10,000`检查，这在时间限制内是微不足道的。 不需要复杂的数据结构或优化。 

一个微妙的细节是瓶子无法自行打开。 检查瓶子是否`i`可以打开，我们必须只考虑具有不同指数的瓶子。 

考虑这个例子：```
2
1 1
2 2
```瓶子 1 可以打开品牌 1，但该功能属于同一个瓶子。 瓶子 2 的行为类似。 两个瓶子都不能被另一个瓶子打开，所以答案是：```
2
```允许自匹配的粗心实现会错误地输出`0`。 

另一个重要的情况是多个瓶子共享同一品牌。```
3
1 5
1 7
2 1
```瓶子 3 可以打开品牌 1，因此两个品牌 1 的瓶子都可以打开。 瓶子3本身带有品牌2，任何瓶子都不能打开品牌2。正确答案是：```
1
```仅检查独特品牌而不是单个瓶子的实施可能会错误计数。 

第三种情况是多个瓶子可以打开同一品牌的情况。```
3
4 4
5 4
4 1
```第一瓶和第二瓶都可以打开品牌4。第三瓶有品牌4，第一瓶可以打开。 每个品牌为 4 的瓶子都应被视为可独立打开。 

## 方法

 最直接的方法是单独检查每个瓶子。 瓶子用`i`，我们扫描所有其他瓶子并检查是否有瓶子`j`有`b[j] = a[i]`。 如果我们找到这样一个瓶子，瓶子`i`是可以打开的。 否则，它有助于答案。 

这种方法是正确的，因为可开启性的定义仅取决于是否存在另一个其开启品牌与该瓶子自己的品牌相匹配的瓶子。 通过检查每一个可能的瓶子`j`，我们准确地测试问题所需的条件。 

对于较大的约束，比较每一对可能会变得昂贵。 和`n = 100`然而，最坏的情况也只有 10,000 次比较，这是很小的。 

人们还可以建立一个包含所有开放品牌的集合`b[i]`并检查会员资格。 唯一的麻烦是禁止自行开放。 由于约束如此之小，成对解决方案更简单并且避免了特殊处理。 

关键的观察是，瓶子的状态仅取决于其品牌是否出现在其他瓶子的打开能力中。 这自然会导致检查所有成对的瓶子。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力配对检查 | O(n²) | O(1) | O(1) | 已接受 |
 | 品牌追踪结构| O(n²) 或 O(n) | O(n) | 已接受但没有必要 |

 ## 算法演练

 1. 阅读`n`并存储所有对`(a[i], b[i])`。 
2. 初始化`answer = 0`。 
3. 每瓶`i`，最初假设它无法打开。 
4. 扫描所有瓶子`j`。 
5. 跳过案例`i == j`，因为瓶子不能用来自行打开。 
6.如果`b[j] == a[i]`，然后装瓶`i`可以用瓶子打开`j`。 将其标记为可打开并停止检查更多瓶子。 
7. 检查所有可能的瓶子后，如果瓶子`i`仍然打不开，增量`answer`。 
8.处理完每个瓶子后，打印`answer`。 

### 为什么它有效

 对于一瓶`i`，问题询问是否存在另一个瓶子的开启能力等于`a[i]`。 该算法检查每个可能的瓶子`j ≠ i`。 如果存在这样的瓶子，则在扫描过程中发现并瓶子`i`被标记为可打开。 如果扫描完成后没有找到瓶子，则输入中的任何位置都不存在这样的瓶子，因此瓶子`i`是不可能打开的。 

由于这种推理独立地应用于每个瓶子，因此最终的计数正是无法打开的瓶子的数量。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())
bottles = [tuple(map(int, input().split())) for _ in range(n)]

answer = 0

for i in range(n):
    brand = bottles[i][0]
    openable = False

    for j in range(n):
        if i == j:
            continue

        if bottles[j][1] == brand:
            openable = True
            break

    if not openable:
        answer += 1

print(answer)
```该程序首先存储所有瓶子描述。 对于每个瓶子，它都会提取其品牌`a[i]`并搜索另一瓶其开瓶品牌等于该价值的瓶子。 

这`i == j`检查是最重要的实施细节。 没有它，一瓶自己的`b[i]`等于`a[i]`会被错误地认为可以自行打开。 

找到有效的开启器后，内部循环立即停止。 这不会改变正确性，但可以避免不必要的比较。 

对于重复的品牌或重复的开启功能不需要特殊处理，因为每个瓶子都经过单独检查。

```每个瓶子只匹配其自己的开启能力。 由于不允许自行打开，所以都不能打开。

 ## 边缘情况

 考虑尽可能最小的输入：```
1
42 42
```该算法检查唯一的瓶子。 内循环跳过自比较，因为`i == j`。 没有找到有效的开场白，所以答案变成`1`。 这符合瓶子不能自行打开的规则。 

考虑一个具有重复品牌的案例：```
3
1 5
1 7
2 1
```对于第一瓶，算法发现第三瓶有`b = 1`，所以是可以打开的。 同样的推理也适用于第二瓶，因为它具有相同的品牌。 第三瓶有品牌`2`，并且没有瓶子具有开启能力`2`，因此只计算该瓶子。 答案是`1`。 

考虑一个循环：```
3
1 2
2 3
3 1
```1号瓶被3号瓶打开，2号瓶被1号瓶打开，3号瓶被2号瓶打开。每次搜索都会找到匹配的开启器，因此计数保持不变`0`。 该算法可以正确处理链和循环，因为它只检查存在性，而不检查打开序列。
