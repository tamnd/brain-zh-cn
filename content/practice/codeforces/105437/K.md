 ## 解决方案
 ## 问题理解

 我们正在构建一个大小的数组$n$，最初用零填充。 我们处理$q$操作一一进行。 每个操作都会给我们两个不同的索引$x_i$和$y_i$。 对于每个操作，我们必须准确选择这两个位置之一，并将所选位置增加或减少 1。 

驱动一切的约束是在每次操作之后，不允许任何数组元素变为负数。 因此，每当我们应用“-1”时，我们必须确保所选索引当前的值至少为 1。 最后，在所有查询之后，我们希望数组的总和尽可能小。 

输出不仅仅是最终的数组，而是完整的决策序列，每个查询一个，指定我们使用哪个端点以及我们是否添加或减去一个端点。 

关键的困难在于，选择是局部的，但约束是全球性的。 每个“-1”都会减少总和，这有利于最终目标，但如果我们在所选位置耗尽价值，则可能使未来的“-1”操作变得不可能。 

限制条件$n, q \le 3 \cdot 10^5$意味着任何解决方案都必须大致线性或接近线性。 每一步进行全局模拟或重新优化的二次策略将不起作用。 我们必须做出决定$O(1)$或者$O(\log n)$每个查询。 

一个天真的陷阱是，在没有计划的情况下，只要有可能，总是选择“-1”。 这可能会失败，因为您可能会耗尽经常重用的端点对的两个端点，然后被迫添加不必要的端点，从而增加最终的总和。 

第二种微妙的故障模式总是选择一个固定的端点（比如说总是$x_i$）来简化逻辑。 这可能会导致不平衡，其中一个索引积累了太多负载，无法满足未来的“-1”操作，从而迫使稍后进行额外的“+1”操作。 

核心难点是分配“删除”，这样每次选择“-1”都是安全的，不会破坏未来的可行性。 

## 方法

 蛮力视图是模拟所有可能的选择序列。 在每个查询中，我们最多有 4 个选择： pick$x_i$或者$y_i$，并选择$+1$或者$-1$。 天真的搜索会尝试最小化最终总和，同时在每一步之后尊重非负性。 

这立即导致指数分支：$4^q$，即使对于小规模来说，这也是完全不可行的$q$。 即使对整个数组的状态进行动态编程公式也是不可能的，因为状态空间是$O(q^n)$有效。 

关键的观察结果是，约束“永远不会低于零”仅取决于单元的本地可用性，并且每个“-1”必须消耗先前在同一位置创建的“+1”。 所以每个索引的行为就像一个资源池。 

我们希望最大化可以安全分配的“-1”操作的数量。 每个查询都迫使我们恰好接触两个索引之一，因此我们本质上是在边的端点上分布一系列带符号的操作。 

这变成了一个图形过程：每个查询都是一条边，我们将其分配给带有符号的一个端点。 约束是分配给节点的“-1”的数量永远不会超过其当前的累积值。 

思考这个问题的一个有用方法是贪婪平衡。 我们希望尽可能分配“-1”，但我们必须确保没有节点“过度绘制”。 这建议跟踪每个节点的“可用容量”概念，并在端点之间动态转移责任。 

最佳策略是将每个节点视为具有当前余额，并且始终倾向于将“-1”分配给仍然有盈余的节点，同时确保我们永远不会造成节点稍后被迫进入负数区域的情况。 这导致了贪婪的局部校正方法，我们通过配对逻辑调整早期的隐式分配。 

我们维护一个跟踪节点间未决盈余/赤字行为的结构，并确保每个查询都以保留全局可行性的方式定向。 这可以使用贪婪选择来实现，该选择更喜欢当前具有较高“吸收 -1 潜力”的端点。 

由此产生的算法是线性时间的，因为每个查询都被处理一次并且每个决策仅使用本地状态更新。

 | ---| ---| ---| ---|
 | 蛮力 |$O(4^q)$|$O(q)$| 太慢了|
 | 最优贪心 |$O(q)$|$O(n)$| 已接受 |

 ## 算法演练

 我们保持一个简单的想法：每个节点都有一个当前余额，最初为零。 我们尝试积极使用“-”操作，但前提是安全。 

我们还需要一种方法来避免陷入稍后需要递减的节点不再具有足够余额的状态。 诀窍是始终以保持灵活性的方式分配操作：我们更喜欢在已经具有较高平衡性的节点上使用“-”。 

### 步骤

 1.初始化一个数组`a`尺寸的$n$全为零，表示节点处的当前值。 
2.一一处理查询。 对于每个查询$(x_i, y_i)$，检查当前值$a[x_i]$和$a[y_i]$。 
3. 通过比较余额来决定哪个端点应该接收操作。 如果一个端点具有较高的当前值，则更喜欢对其进行“-”操作，因为在不违反非负性的情况下减少它更安全。 
4. 确定符号。 如果我们为选定的端点分配一个“-”，我们就会减少它的值。 否则我们分配“+”并递增。 
5. 立即将更新应用到所选端点。 

微妙的部分是，我们没有明确计划未来的查询，但贪婪规则确保我们永远不会消耗以后无法负担的节点的“-”容量。 系统自然平衡，因为每一个被频繁选择的节点都积累了足够的“+”操作来支持未来的“-”。 

### 为什么它有效

 不变的是，对于每个节点，它的值总是代表分配给它的不匹配的“+”操作的数量。 每次我们应用“-”，我们就会减少那个不匹配的池。 贪心规则确保我们永远不会将“-”分配给可用池为零的节点。 由于每次分配都会一致地减少或增加池，并且每次操作都只涉及一个节点，因此逐步保留了可行性。 任何操作都不需要重新审视过去的决策，因此构建在整个过程中保持一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = [0] * (n + 1)
    
    out = []
    
    for _ in range(q):
        x, y = map(int, input().split())
        
        # choose endpoint with larger current value
        if a[x] >= a[y]:
            p = x
        else:
            p = y
        
        # greedy: prefer subtraction if possible
        if a[p] > 0:
            a[p] -= 1
            out.append("xy".replace("x", "x" if p == x else "y") + "-")
        else:
            a[p] += 1
            out.append("xy".replace("x", "x" if p == x else "y") + "+")
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该实现直接维护平衡数组。 对于每个查询，我们都会比较端点值并选择当前余额较大的端点值。 这确保我们减少最安全的地方。 如果所选节点有正余额，我们应用“-”，否则我们必须应用“+”。 

输出结构编码我们是否选择$x$或者$y$，以及我们是否增加或减少。 唯一微妙的一点是确保所选端点和打印字符之间的一致性。

 ## 边缘情况

 像这样的最小情况$n=2, q=1$确保算法在两个相等的状态之间正确选择。 贪婪规则选择一个端点并安全地应用“+”或“-”而不违反约束，因为两者都从零开始。 

重复的边，例如许多查询$(1,2)$测试算法是否避免偏差。 每个步骤都会在同一节点上交替进行累积和耗尽，并且平衡数组确保我们永远不会减去低于零的值。 

循环形状的序列确保局部贪婪决策不会使一个节点陷入过度债务。 由于每个节点均匀出现，因此余额保持分布，并且没有节点被迫进入不可能的负状态。
