 ## 解决方案
 ## 问题理解

 我们得到一张纸，然后使用全长直切反复将其分割。 每次剪切要么从左到右穿过整个当前工作表，要么从上到下穿过整个当前工作表。 重要的细节是，切割总是跨越整个纸张，因此它们会切片它们相交的每个现有部分。 

在执行一些水平和垂直切割序列后，板材变成矩形块的网格。 问题是总共需要多少切割才能使最终的碎片数量恰好满足$n$。 

输入给出一个整数$n$，并且我们必须输出所需的最小整张切割数，以便最终的片数等于$n$。 

约束条件$n \le 10^6$立即排除任何试图模拟剪切序列或搜索配置的行为。 任何探索分割网格的方法中的一小部分的方法都会失败，因为可能的切割分布的数量随着切割数量的增加而组合增长。 

一个微妙的点是，每次切割都会根据当前状态以乘法方式增加碎片数量，而不仅仅是加法。 这就是“只是分裂，直到达到$n$” 不可靠。

 一些边缘案例有助于澄清容易误解的内容。 如果$n = 2$，一次切割就足够了：一次水平或垂直切割恰好产生两块。 如果$n = 3$，两次切割就足够了，例如两次垂直切割分成三条。 如果$n = 100$，存在一种对称结构，其中沿两个方向重复切割总共使用 20 次切割产生 10 x 10 网格。 

一个常见的错误是假设我们可以贪婪地添加切割并始终线性控制块数。 这会失败，因为一旦使用了两个方向，每个新的切割都会在现有段上相乘。 

## 方法

 如果我们尝试直接推理，我们可以从维护网格的角度来思考。 假设我们做$h$水平切割和$v$垂直切割。 每次水平切割都会使水平条的数量增加一，因此在所有水平切割之后我们有$h+1$行。 同样，我们得到$v+1$垂直切割的列。 每行与每列相交，因此总件数为$(h+1)(v+1)$。 

这将问题从动态切割过程简化为纯粹的因式分解问题：我们想要表示$n$作为两个正整数的乘积，每个正整数至少为 1，并最小化$(h+v)$在哪里$h+1$和$v+1$就是这些因素。 

让$a = h+1$和$b = v+1$。 然后$ab = n$，切割次数变为$h+v = a+b-2$。 所以任务变成寻找一个因子对$n$最大限度地减少$a+b$。 

蛮力的想法是尝试所有对$a, b$这样$a \cdot b = n$, 计算$a+b$，并取最小值。 这是正确的，因为每个有效的切割策略都完全对应于某些因式分解$n$。 问题是性能：检查所有除数$n$会花费$O(n)$，这对于$10^6$。 然而，我们只需要检查除数$\sqrt{n}$，因为因子对围绕平方根镜像。 

关键的见解是最佳解决方案更喜欢平衡因素。 对于固定乘积，当因子尽可能接近时，总和最小，因此我们只需要扫描可能的除数$\sqrt{n}$。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 太慢了|
 | 最优（平方因子扫描）| O(\sqrt{n}) | O(\sqrt{n}) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 迭代所有整数$i$从 1 到$\lfloor \sqrt{n} \rfloor$。 我们只考虑平方根，因为任何大于$\sqrt{n}$具有在较小范围内已经看到的互补因子。 
2. 对于每个$i$，检查是否$i$划分$n$。 如果没有，则继续下一个候选，因为它无法形成有效的网格维度。 
3.如果$i$划分$n$，计算配对因子$j = n / i$。 这给出了有效的分解$n = i \cdot j$，对应于一个网格$i$行和$j$列（或反之亦然）。 
4. 将它们转换为切割：行需要$i-1$水平切割和列需要$j-1$垂直切割。 该因子对的总成本为$i + j - 2$。 
5. 跟踪最小值$i + j - 2$在所有有效因子对上。 这代表了最佳的分体配置。 
6. 输出找到的最小成本。 

### 为什么它有效

 每个水平和垂直切割序列都会产生一个网格。 行数完全由水平切割决定，列数由垂直切割决定，与顺序无关。 因此任何最终配置都唯一对应于一对$(a, b)$和$ab = n$。 由于所有这些对都是通过除数扫描枚举的，因此我们永远不会错过有效的配置。 最小化所有对的切割保证了最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n = int(input())

best = float('inf')

i = 1
while i * i <= n:
    if n % i == 0:
        j = n // i
        best = min(best, i + j - 2)
    i += 1

print(best)
```该代码直接实现了因子对解释。 循环结束$i$枚举潜在的行数，同时$j$是对应的列数。 每个有效除数对都使用以下方法转换为切割计数$i + j - 2$，它来自于每个维度减去一次切割以将碎片转换为切割。 

一个微妙的细节正在初始化`best`到无穷大，以便正确考虑每个有效因子对。 另一个重要的一点是只有在确认整除性之后才使用整数除法，这可以避免错误的对。

 ## 边缘情况

 对于$n = 2$，唯一的因子对是$1 \cdot 2$。 算法检查$i = 1$, 发现$j = 2$，并计算$1 + 2 - 2 = 1$。 这与分成两部分所需的单次切割相匹配。 

对于像这样的素数$n = 3$或附近的一个大素数$10^6$，除 1 之外不存在除数。 循环仅在以下时刻触发$i = 1$，强制配置一行并且$n$列。 计算结果变为$n - 1$，这相当于将所有切口沿一个方向堆叠，这与形成平衡网格的不可能性一致。 

对于完美的正方形，例如$n = 100$, 除数$i = 10$产生对称构型。 该算法评估两者$10 \times 10$和其他不对称对，但对称对最小化$i + j - 2$，给出 18。这证实了对除数的搜索正确地捕获了最佳平衡点。
