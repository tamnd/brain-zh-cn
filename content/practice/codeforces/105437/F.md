 ## 解决方案
 ## 问题理解

 我们有一组多张卡片，每张卡片都带有一个整数值。 Monocarp 通过一张一张地挑选牌来构建序列，并在拿走它们时将它们从牌堆中移除。 第一张牌可以自由选择，但接下来的每一张牌都受到最后一张牌的值的限制：他只能拿一张具有相同值或正好一个更大值的牌。 

整个序列还有一个额外的限制：在所有拿走的牌中，不同值的数量不得超过 k。 一旦 Monocarp 无法根据这些规则合法地拿走另一张牌，该过程就会停止。 任务是通过选择起始牌并以最佳方式打牌来最大化他可以拿多少张牌。 

约束最大为 n = 200000，这排除了对所有起点或所有值子集进行任何二次模拟。 任何重复重新扫描数组或尝试独立模拟所有可能的贪婪启动的操作都会太慢。 解决方案必须在预处理后将问题简化为线性或近线性扫描。 

当值分散但仍然形成长的可用链时，就会出现微妙的边缘情况。 例如，如果 k = 2 并且数组是`[1, 100, 2, 3, 101]`，从起点贪婪延伸的幼稚策略可能无法认识到最佳游戏取决于排序后选择连续的值范围，而不是原始顺序。 另一个失败案例来自假设我们必须始终从最小值开始； 从中间值开始可以产生更长的可用段，因为我们只能向上移动+1。 

关键的隐藏结构是，取值的序列始终是非递减的，并且每一步最多增加一个，因此整个过程发生在整数值的连续区间内，而每个值内部的实际顺序并不重要。 

## 方法

 暴力方法会尝试每一张可能的起始卡，然后贪婪地或回溯地模拟游戏：从选定的开始，重复选择任何值为 x 或 x+1 的可用卡，同时跟踪出现了多少个不同的值。 如果我们扫描下一张有效卡或在没有优化的情况下维护存储桶，则每次模拟可能会花费 O(n) 时间，并且对所有起始位置执行此操作会导致 O(n^2)，这对于 200000 个元素来说太大了。 

关键的观察是，规则仅取决于价值观，而不取决于立场。 一旦我们将相同的值分组在一起，问题就变成了值的频率以及选择一个连续的值段，我们模拟拿走所有卡片，但有一个限制，即我们只能在过程的任何有效段中“使用”最多 k 个不同的值。 

如果我们对不同的值进行排序并压缩它们，每个值都有一个频率。 任何有效的游戏都对应于选择一个连续值的窗口，并且在该窗口内，Monocarp 可以从左到右遍历，消耗所有卡牌。 最多 k 个不同值的约束意味着不同值的窗口大小必须至多为 k，但由于移动被限制为 x 或 x+1 转换，一旦我们包含值 x，如果它存在于所选结构中，我们只能继续到 x+1。 这有效地将最优策略转变为选择一段连续整数并对它们的频率求和，同时通过限制我们传递的不同值的数量来确保我们遵守 k 界限。 

这简化为排序唯一值上的经典滑动窗口：我们维护一个邻接有效的连续值窗口，并确保内部不同值的数量不超过 k，然后最大化该窗口中的总频率。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n^2) | O(n^2) | O(n) | 太慢了|
 | 排序 + 在值上滑动窗口 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

1. 首先，将相同的值分组并计算它们的频率。 这会删除位置信息，因为只有每个值存在多少个副本才能最大化序列的长度。 
2. 按升序对不同值进行排序，保持它们的频率一致。 排序是必要的，因为只允许在相等或连续的整数之间进行转换，因此值空间中的顺序定义了所有有效的移动。 
3. 在已排序的唯一值上使用两个指针来维护 Monocarp 可以遍历的候选值窗口。 右指针通过按升序添加新值来扩展窗口。 
4. 维护当前窗口内的卡片总数作为频率之和。 这表示如果 Monocarp 致力于这组价值观，他可以采取多少步骤。 
5. 确保窗口遵循游戏引起的约束：值必须保持连续，因此如果连续值之间的间隙超过 1，我们将从当前值开始重置窗口。 这是因为禁止大于 +1 的跳转，因此断开的值不能在有效序列中共存。 
6. 由于 Monocarp 最多只能包含 k 个不同的值，因此只要窗口的大小超过 k，就缩小窗口的左侧。 这会将不同值的数量保持在允许的限制内。 
7. 在每一步中，用在任何有效窗口中观察到的最大总频率更新答案。 

这样做的原因是任何有效的游戏路径都对应于选择连续整数值的一段，并且在该段内 Monocarp 可以获取这些值的所有卡牌。 k 约束限制了该段在不同值方面的宽度，并且转换规则将其限制为连续整数。 因此，每一个有效的播放都由一个有效的滑动窗口来表示，并且每个滑动窗口都对应于一个有效的播放。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    freq = defaultdict(int)
    for x in a:
        freq[x] += 1

    vals = sorted(freq.items())  # (value, count)

    left = 0
    curr_sum = 0
    best = 0

    for right in range(len(vals)):
        if right > 0 and vals[right][0] != vals[right - 1][0] + 1:
            left = right
            curr_sum = 0

        curr_sum += vals[right][1]

        while right - left + 1 > k:
            curr_sum -= vals[left][1]
            left += 1

        best = max(best, curr_sum)

    print(best)

if __name__ == "__main__":
    solve()
```该代码首先将输入压缩为频率图。 这很重要，因为答案仅取决于每个值的计数，而不取决于它们的位置。 

对值进行排序后，循环在连续整数上维护一个滑动窗口。 复位条件`vals[right][0] != vals[right - 1][0] + 1`强制执行我们不能弥合大于 1 的间隙的规则，因为游戏只允许从 x 移动到 x 或 x+1。 

第二个约束是限制不同值的数量，当窗口超过 k 个不同值时，通过缩小窗口来强制执行。 运行总和`curr_sum`跟踪当前有效段中有多少张牌，这正是有效播放序列的长度。

 ### 示例 1

 输入：```

```频率压缩后，我们得到值：`2:2, 3:3, 4:3, 5:2`我们模拟：

 | 对| 价值| 左| 窗口值| 总和| 行动|
 | ---| ---| ---| ---| ---| ---|
 | 0 | 2 | 0 | [2] | 2 | 开始 |
 | 1 | 3 | 0 | [2,3]| 5 | 展开 |

 | 3 | 5 | 0→1 | [3,4,5]| 8 | 缩小到 k=2 |

 最好是8。 

这显示了窗口如何始终代表连续的价值链，以及 k 约束如何迫使我们删除最左边的值。

 | ---| ---| ---|
 | 时间 | O(n log n) | O(n log n) | 对不同值进行排序占主导地位，滑动窗口是线性的 |

 ## 边缘情况

 一个关键的边缘情况是输入中的值不连续但仍然允许部分链。 用于输入`6 2 / 1 100 2 3 101 4`，只要遇到大于 1 的间隙，算法就会正确重置。`[1]`，然后重置于`100`，然后稍后构建`[2,3,4]`总和为 3，在 k = 2 约束下是最优的。 

另一种边缘情况是 k 足够大以包含所有不同的连续值。 为了`8 3 / 1 1 2 2 3 3 4 4`，窗口永远不会超过 k，并且算法将所有频率累积到单个段中，正确地生成 8。 

最后，当所有值都相同时，窗口就很简单并且始终有效。 该算法永远不会触发重置或缩小，答案很简单，即n，符合每张牌都可以连续拿走而不违反任何规则的事实。
