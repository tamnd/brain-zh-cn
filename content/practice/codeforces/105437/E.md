 ## 解决方案
 ## 问题理解

 我们收到了许多独立的查询。 每个查询指定一对索引$n$和$k$，我们被要求从三角表中计算一个值$C$以非标准方式生成的。 

该表是逐行构建的。 每行$n$开始于$C[n][0] = 1$, 结束于$C[n][n] = 1$，并且每个内部值都是使用来自同一行和前一行的值形成的，特别是来自同一行中的左邻居和对角线左上角条目的值。 

这与通常的二项式系数表不同，其中每个值取决于其正上方的两个条目。 在这里，信息也在行内水平流动，这改变了三角形的整个结构。 

任务是计算$C[n_i][k_i]$最多为$10^5$查询，与$n_i$最多$10^5$。 由于每个值可能很大，因此必须以模数形式返回结果$10^9 + 7$。 

这些约束意味着任何显式构造表的解决方案都是不可能的。 完整的 DP 表需要$O(n^2)$时间和记忆，远远超出了我们所能承受的范围$n = 10^5$。 即使天真地计算单行也是如此$O(n)$，并且对于许多查询来说这样做仍然太慢。 

复发本身出现了一个更微妙的问题。 因为递归同时使用了两者$C[n][k-1]$和$C[n-1][k-1]$，值在行之间重复传播。 这意味着帕斯卡三角形的天真的直觉并不适用，并且解释中的小错误会导致完全不同的序列。 

一个典型的陷阱是假设这只是二项式系数。 例如，对于$n = 4$,$k = 2$，正确的二项式系数是$6$，但实际的递归产生$4$。 另一个常见的误解是假设仅依赖于$k$，而实际上必须仔细推导结构。 

## 方法

 蛮力方法是将整个表构建到最大$n$在使用给定递归的查询中看到。 对于每一行$n$，我们计算每个$C[n][k]$从$k = 1$到$n - 1$，然后直接回答问题。 这很简单并且忠实于定义。 

然而，这种方法执行大量操作。 外循环运行至$10^5$，内循环也运行到$10^5$，导致周围$10^{10}$最坏情况下的更新。 每次更新都是恒定时间，但规模仍然远远超出任何可行的限制。 

关键的见解来自于观察值如何跨行传播。 展开一次递归会显示一个隐藏的前缀结构：$$C[n][k] = C[n][k-1] + C[n-1][k-1]$$在同一行内重复展开第一项可得出：$$C[n][k] = C[n][0] + \sum_{j=1}^{k} C[n-1][j-1]$$自从$C[n][0] = 1$，这变成：$$C[n][k] = 1 + \sum_{i=0}^{k-1} C[n-1][i]$$这表明每个条目都是由前一行的前缀和确定的。 该结构足够强大，可以将二维过程折叠成一个简单的图案。 计算几行揭示了稳定性：对于固定的$k$， 一次$n$变得足够大，该值停止变化。 

通过计算小案例，我们可以看到：

 第 2 行：$1, 2, 1$第 3 行：$1, 2, 4, 1$第 4 行：$1, 2, 4, 8, 1$第 5 行：$1, 2, 4, 8, 16, 1$对于所有有效的$k < n$，该值变为$2^k$，独立于$n$。 仅最后一个元素$C[n][n]$保持固定在$1$。 

这将每个查询减少为直接功率计算。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力破解 DP 表 |$O(n^2)$|$O(n^2)$| 太慢了|
 | 观察公式$2^k$|$O(t \log MOD)$|$O(1)$| 已接受 |

 ## 算法演练

 一旦模式被识别，计算就变成了直接评估问题。 

1. 阅读所有查询$n_i, k_i$。 的价值$n_i$除了确认之外不再影响计算$k_i < n_i$。 
2. 预先计算 2 的幂直至最大可能值$k$使用模幂或迭代加倍。 这避免了每个查询重新计算幂运算。 
3. 对于每个查询，输出$2^{k_i} \bmod (10^9 + 7)$。 

这样做的原因是，递归导致每一行都像前一行的累积和一样，并且恒定初始结构的重复累积求和会产生指数增长$k$同时消除对$n$在前几行之后。 

### 为什么它有效

 递归将每一行转换为前一行的前缀和，并在每行的开头具有固定的边界条件 1。 这种重复的前缀会导致值随着每次增加而加倍$k$，独立于$n$， 一次$n$足够大以支撑该柱。 结果，表稳定为跨列的简单指数序列，并且行索引仅影响最后一个边界元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modpow(base, exp):
    result = 1
    while exp:
        if exp & 1:
            result = result * base % MOD
        base = base * base % MOD
        exp >>= 1
    return result

t = int(input())
n = list(map(int, input().split()))
k = list(map(int, input().split()))

for i in range(t):
    print(modpow(2, k[i]))
```该解决方案完全依赖于快速求幂。 的数组$n$和$k$被读取一次，并且仅$k$用于计算，因为导出公式消除了对$n$对于所有有效输入。 

模幂函数以迭代方式实现，以避免递归开销并确保每个查询的对数运行时间。

import sys, io

MOD = 10**9 + 7

def modpow(base, exp):
    result = 1
    while exp:
        if exp & 1:
            result = result * base % MOD
        base = base * base % MOD
        exp >>= 1
    return result

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())

    k = list(map(int, input().split()))

 ## 边缘情况

 一个重要的边缘情况是当$k = 1$。 复发仍然产生$C[n][1] = 2$对于所有有效的$n \ge 2$，匹配$2^1$。 直接 DP 实现可能会错误地初始化或跳过此列，但派生公式会统一处理它。 

另一个边缘情况是当$k = n - 1$。 即使这接近边界，该值仍然遵循$2^{n-1}$。 幼稚的基于行的 DP 可能会错误地覆盖或错误处理边界传播，但封闭形式保持一致。 

最后，对于大$k$，指数增长完全由模幂处理，因此不存在溢出或中间数组爆炸的风险。
