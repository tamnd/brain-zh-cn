 ## 解决方案
 ## 问题理解

 我们得到一个偶数长度的数组，在概念上分为两个相等的部分：左半部分和右半部分。 我们被允许执行一次交换，但交换受到严格限制。 我们必须从左半部分选择一个索引，从右半部分选择一个索引，并交换它们的值。 

完成这次交换后，我们希望左半部分的总和恰好等于右半部分的总和。 任务是确定这样的交换是否存在，如果存在，则输出任何有效的头寸对。 

最突出的限制是数组大小最多为 200,000。 任何尝试跨越一半的所有对的解决方案都需要大约 (n/2)^2 次检查，在最坏的情况下大约会变成 10^10 次操作，远远超出 2 秒内的可行限制。 这立即排除了暴力配对的可能性。 

这些值本身的界限是 10,000，这个值足够小，以至于基于频率的推理或散列技术变得合理。 

一个微妙的点是我们必须执行一次交换，而不是最多执行一次。 因此，即使数组已经有相等的一半，我们仍然需要找到一个保持相等而不是不执行任何操作的交换。 

天真的推理的失败模式是假设我们可以从左侧选择任何元素，并将其与右侧的某些元素贪婪地匹配，从而在本地平衡总和。 例如，尝试独立匹配差异会忽略全局总和约束，因为交换同时影响两半。 

另一个陷阱是忘记交换必须跨越一半。 即使可以平衡金额，也不允许在一半内进行有效的内部交换。 

## 方法

 一种直接的方法是尝试每一对 (i, j)，其中 i 位于左半部分，j 位于右半部分，模拟交换，然后重新计算两个半部分的和。 如果简单地重新计算，每次检查的成本为 O(n)，如果我们维护前缀和，则每次检查的成本为 O(1)。 即使进行 O(1) 检查，我们仍然有 O(n^2) 对，这大约是 10^10 次操作，太慢了。 

为了改进，我们用代数方式重写了交换的效果。 令初始左和为S_L，右和为S_R。 假设我们将左侧的值 x 与右侧的值 y 交换。 交换后，左边的和变为S_L - x + y，右边的和变为S_R - y + x。 我们想要：

 S_L - x + y = S_R - y + x

 重新排列给出：

 S_L - S_R = 2(x - y)

 这是关键的减少。 整个问题变成了找到一对 (x, y)，使得它们的差异由两半之间的全局不平衡来固定。 

令 D = S_L - S_R。 那么我们需要：

 x - y = D / 2

 这立即意味着 D 必须是偶数，否则不存在解。 

现在任务变成：在左半部分找到 x，在右半部分找到 y，使得 y = x - D/2。 由于值是有界的，并且我们只需要成员资格检查，因此我们可以将右半部分存储在哈希集或频率图中，并测试每个左元素。 

这减少了从索引上的配对搜索到位置簿记的值匹配的问题。

 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

1. 计算左半部分之和与右半部分之和。 它们之间的差异是唯一重要的全局信息，因为每次交换都会对称地影响两半。 
2. 计算 D = S_L - S_R。 如果D是奇数，则立即停止。 没有整数对 (x, y) 可以满足 x - y = D/2，因此没有交换可以平衡两半。 
3. 构建从右半部分的值到其索引的映射。 我们只需要知道一个值是否存在以及它出现在哪里，因为我们可以自由选择任何有效的位置。 
4. 计算目标差值 k = D / 2。我们现在想要找到一个左元素 x，使得 (x - k) 存在于右半部分。 这直接对之前导出的交换条件进行编码。 
5. 迭代左半部分。 对于值为 x 的每个位置 i，检查 x - k 是否存在于右半地图中。 如果是，我们立即返回（i，对应的索引）。 这是有效的，因为它满足派生的相等条件，保证交换后的总和平衡。 
6. 如果扫描左半部分后没有找到这样的对，则输出NO。 

### 为什么它有效

 该变换将交换效应减少为所选值中的单个线性方程。 任何有效的交换必须满足 x - y = D/2，并且满足此方程的任何对在代回更新后的总和时必然等于两个半和。 由于我们将每个候选左值与所有可能的匹配右值进行检查，因此我们不会错过任何可行的交换。 

正确性取决于交换仅通过精确减去和加上交换值来改变总和。 位置之间没有其他相互作用，因此该方程充分表征了可行性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    mid = n // 2
    left = a[:mid]
    right = a[mid:]
    
    sum_left = sum(left)
    sum_right = sum(right)
    
    diff = sum_left - sum_right
    
    if diff % 2 != 0:
        print("NO")
        return
    
    k = diff // 2
    
    pos_right = {}
    for i, val in enumerate(right):
        if val not in pos_right:
            pos_right[val] = i + 1  # 1-based index in right half
    
    for i, val in enumerate(left):
        need = val - k
        if need in pos_right:
            print("YES")
            print(i + 1, pos_right[need] + mid)
            return
    
    print("NO")

if __name__ == "__main__":
    solve()
```该解决方案首先将数组分成两半并直接计算它们的总和。 关键的实现细节是使用相对于该段的基于 1 的索引单独维护右半部分的索引，然后通过添加转换回全局索引`mid`。 

计算值`k`是和之间的半差，我们用它来将条件转化为查找问题。 对于每个左元素，我们计算右半部分所需的伙伴值，并使用字典在恒定时间内检查是否存在。 

一个常见的陷阱是在报告右侧位置时忘记移动索引。 另一种是计算错误`k`作为全部差异而不是一半，这打破了从交换效应导出的方程。 

## 工作示例

 ### 示例 1

 输入：```
6
4 1 2 6 7 6
```左半边是`[4, 1, 2]`，右半部分是`[6, 7, 6]`。 

| 步骤| S_L | S_R | 差异| k | 行动|
 | ---| ---| ---| ---| ---| ---|
 | 初始化| 7 | 19 | 19 -12 | -6 | 计算总和 |
 | 检查 | 7 | 19 | 19 -12 | -6 | 建立正确的地图|
 | 扫描 i=1 | 4 | - | - | - | 需要 = 4 - (-6) = 10 未找到 |
 | 扫描 i=2 | 1 | - | - | - | 需要 = 1 - (-6) = 7 已找到 |
 | 停止| - | - | - | - | 输出交换|

 我们发现将左侧的值 1 与右侧的值 7 交换可以平衡总和。 交换后，两半之和为 13，确认导出条件准确无误。 

### 示例 2

 输入：```
4
5 4 3 5
```左半边是`[5, 4]`，右半部分是`[3, 5]`。 

| 步骤| S_L | S_R | 差异| k | 行动|
 | ---| ---| ---| ---| ---| ---|
 | 初始化| 9 | 8 | 1 | 0.5 | 0.5 diff 为奇数 |
 | 停止| 9 | 8 | 1 | - | 输出号 |

 由于差值是奇数，因此任何整数交换都不能满足 x - y = D/2，并且算法会提前正确终止。

 ## 边缘情况

 一种边缘情况是阵列已经平衡。 例如：

 输入：```
4
1 2 2 1
```这里两半的总和为 3。算法计算 diff = 0，因此 k = 0。这意味着我们需要 x = y，因此任何相同值的跨半对都是有效的。 右半部分的哈希图确保如果两侧都存在值，我们会立即找到有效的交换，即使总和已经相等。 

另一种情况是存在多个相同的值。 该映射仅为每个值存储一个索引，但这已经足够了，因为任何出现的值都是有效的。 即使存在多个交换，返回第一个找到的对仍然满足条件，因为方程仅取决于值，而不取决于位置。
