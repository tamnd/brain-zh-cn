 ## 解决方案
 ## 问题理解

 我们从一系列红色、黄色和绿色的球开始，并带有计数`a`,`b`， 和`c`。 我们可以重复选择任何一个球并将其重新涂成其他两种颜色之一。 每次重绘操作仅更改一个球及其颜色，而球的总数保持不变。 

目标是达到一种配置，其中恰好存在两种颜色并且这两种颜色以相等的数量出现。 换句话说，在所有重新绘制之后，其中一种颜色必须完全消失，而剩下的两种颜色必须分别包含所有球的一半。 

球的总数固定为`N = a + b + c`。 如果我们最终使用两种具有相同计数的颜色，则每种颜色都必须包含`N / 2`球，所以`N`必须是均匀的。 这已经引入了结构约束：如果球的总数是奇数，则任何重新绘制序列都不能产生两个相等的整数大小的组。 

边界允许每个`a`,`b`， 和`c`大至一百万。 这使得任何模拟重新绘制或在单个球上尝试所有配置的方法都是不可能的，因为球的总数可能达到三百万个。 我们需要一个在每个测试用例的恒定或对数时间内工作的解决方案。 

一些微妙的边缘情况值得牢记。 如果所有球已经属于两种颜色但不均匀，例如`a = 2, b = 5, c = 4`，答案可能仍然是不可能的，因为总和是奇数。 另一个微妙的情况是，当所有三种颜色都相等时，不会自然发生颜色消除，但如果满足奇偶条件，我们仍然可以强制一种颜色以最佳方式消失。 

## 方法

 强力策略是直接模拟重绘操作。 在每一步中，我们都可以从当前过量的颜色中挑选一个球，并将其重新绘制为不足的颜色。 虽然这最终会在可能的情况下达到有效的配置，但可能的序列数量随着球的数量呈指数增长。 即使是一个包含几百万个球的测试用例也使得这完全不可行。 

更结构化的视图来自于重新构建最终状态。 我们对操作顺序不感兴趣，只对最终的颜色分配感兴趣。 最终的配置始终包括从三种颜色中选择两种颜色，并将所有球分配到这两种颜色中，以便每个球都以精确的颜色结束`N / 2`球。 

所以问题就变成了：对于每对颜色，我们必须重新绘制的最小球数是多少，才能将初始分布转换为这两种颜色之间的平衡分配？ 

假设我们固定一对，例如红色和黄色，并强制将所有绿色球重新分配为红色或黄色。 最佳策略是保留尽可能多的已经正确着色的球。 任何分配到红色的红球都已经是正确的，分配到黄色的任何黄球也是正确的。 绿色球永远不能保留，因为最终配置中不存在绿色。 

因此，对于选定的一对，已经正确的球的最佳可能数量取决于有多少红球可以保持红色，有多少黄球可以保持黄色，前提是两种最终颜色都准确达到`N / 2`。 

关键的简化是我们永远不需要显式模拟重新分配。 我们只需要计算有多少个球可以保持原来的颜色，同时尊重容量`N / 2`对于两种选定的颜色中的每一种。 

这减少了检查所有三对可能的颜色并获得最佳结果的问题。

 ## 算法演练

 我们定义`N = a + b + c`和`half = N / 2`。 

1.如果`N`为奇数，返回`-1`立即地。 有效的最终状态需要两个相等的整数组，其总和为`N`，这是不可能的，当`N`很奇怪。 
2. 考虑两种现存颜色的每种可能选择：`(R, Y)`,`(R, G)`， 和`(Y, G)`。 
3. 对于固定对，计算有多少个球可以保持原来的颜色。 例如，如果我们选择`(R, Y)`，那么只有红球保持红色和黄球保持黄色才有助于保持不变的计数。 
4. 对于所选对中的每种颜色，我们最多可以保留`min(original_count, half)`那种颜色的球。 这是因为即使一种颜色的含量超过`half`最初，我们不能保留超过`half`其中，因为该颜色的最终目标正是`half`。 
5. 将这些贡献相加，得到该对保留球的数量。 所需的重绘操作次数为`N - kept`。 
6. 取所有三对的最小重涂成本。 

这种贪婪计数起作用的原因是，除了固定容量约束之外，每种颜色对每个目标桶的贡献是独立的`half`。 We always prefer to keep a ball in its original color because repainting can only increase the cost, and there is no benefit to moving a correctly placed ball elsewhere when capacity is still available.

 ## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    a = int(input())
    b = int(input())
    c = int(input())

    n = a + b + c
    if n % 2 == 1:
        print(-1)
        return

    half = n // 2

    def cost(x, y):
        kept = min(x, half) + min(y, half)
        return n - kept

    ans = min(
        cost(a, b),
        cost(a, c),
        cost(b, c)
    )
    print(ans)

if __name__ == "__main__":
    solve()
```该实现直接对观察结果进行编码，即只有两种幸存颜色的最终选择很重要。 辅助函数`cost(x, y)`通过计算有多少个球可以保持在这两种颜色的原位，计算固定对的最佳重涂计数。 减去`n`将保留的球转换为所需的重绘操作。 

一个微妙的点是我们从来没有明确地跟踪里面的第三种颜色`cost`。 这是有意为之的，因为无论分布如何，排除颜色的每个球都必须重新绘制，因此它不会影响两种所选颜色之间的优化。

 ### 示例 1

 | （R，Y）| 最小值(2,3)=2 | 最小值(3,3)=3 | 5 | 1 |

这表明即使绿色存在，最好消除它并平衡其他两种颜色。 

### 示例 2

 输入：`a = 2, b = 5, c = 4`这里`N = 11`，这很奇怪。 

自从`half`不会是一个整数，不可能将所有球分成相等的两个组。 任何重画序列都不能改变奇偶校验，因此输出是`-1`。 

此案例证实奇偶校验是独立于重新分配逻辑的硬可行性约束。

def run(inp: str) -> str:

 ## 边缘情况

 当三种颜色都存在且总数为奇数时，例如`2, 5, 4`，算法立即拒绝这种情况，因为没有重新分配可以修复奇偶校验。 计算永远不会进行配对评估，因此不存在产生误导性最小值的风险。 

例如，当一种颜色为零时`4, 4, 0`，这对`(R, Y)`产量`min(4,4) + min(4,4) = 8`，所以成本为零。 这正确地反映了系统已经满足要求，无需任何重新绘制。 

当所有值都相等时，例如`10, 10, 10`，每对行为对称，结果仅取决于容量`half`。 该算法自然地收敛于重新绘制一组全彩球，这与最佳重新分配策略相匹配。
