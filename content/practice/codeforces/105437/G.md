 ## 解决方案
 ## 问题理解

 我们在数轴上得到一组固定点，包括端点 0 和 10^9，它们代表城市中现有的商店位置。 在这些已占用的位置之间，我们可以在当前为空的整数坐标处插入最多 m 个附加存储。 限制是两个商店不能占据相同的坐标。 

一旦放置了所有商店，我们就会查看商店位置的排序列表并考虑每对连续商店。 每个这样的对形成一个线段，该线段的长度是两个相邻商店之间的距离。 目标是在放置新商店时使这些相邻距离中的最大距离尽可能小。 

这从根本上来说是一个间距优化问题：我们并不是试图最小化总距离或平均间隙，而是试图最小化插入额外点后的最差间隙。 

这些约束允许最多 200,000 个现有存储和 200,000 个附加存储，因此任何尝试直接模拟插入或重复调整间隙的解决方案都会太慢。 对所有间隙进行二次方法或对单独模拟每个插入的优先级结构进行重复贪婪更新的风险为 O((n+m) log n) 或更糟，这是临界值，但仍然没有必要。 关键要求是对所有插入进行聚合推理，而不是逐一推理。 

当贪婪直觉应用不正确时，就会出现微妙的失败情况。 假设有一个巨大的间隙和几个较小的间隙。 一个幼稚的策略可能总是重复插入最大的当前间隙，但是如果没有正确地模拟间隙在分割时如何非线性缩小，这可能会导致关于每个段应接收多少点的错误决策。 

例如，如果我们有一个大小为 10 且 m = 1 的间隙，则答案为 5，而不是 9。如果我们有两个大小为 10 且 m = 1 的间隙，则最佳放置取决于全局比较，而不是孤立的局部改进。 这表明，每个差距必须被视为分配给它的点数的函数，而不是我们贪婪地一步步修复的东西。 

## 方法

 最初的暴力破解想法是模拟逐个添加商店的过程。 在每一步中，我们计算所有相邻的间隙，选择最大的间隙，通过在中间插入一个存储来分割它，然后重复此 m 次。 每次插入都需要扫描所有间隙或维护间隙的优先级队列。 即使使用堆，m 次插入中的每一次都会花费对数时间，并且每次拆分都需要仔细重新计算段长度。 这导致了 O((n + m) log n) 左右的复杂性，这已经很紧张了，更重要的是，它在概念上仍然效率低下，因为它将问题视为顺序的，而最佳配置仅取决于每个段的最终计数。 

关键的观察结果是，一旦我们决定在其中放置多少个新商店，连续商店之间的每个初始间隙都会独立演变。 如果一个段的长度为 g，并且我们在其中放置了 k 个新商店，则它会被分为 k+1 个子段。 最好的可能排列是均匀间隔，得到的最大子段长度是 g 除以 k+1 的上限。 这将问题解耦：我们不决定确切的位置，而只决定每个间隙接收多少插入。

这种结构建议扭转观点。 我们不是分布 m 个存储并检查所得的最大间隙，而是猜测候选最大允许间隙 L，并询问是否可以确保所有最终相邻距离至多为 L。对于每个原始间隙 g，我们计算需要多少个新点，以便没有子间隙超过 L。如果 g 太大，则必须将其分割成足够多的块，并且可以为每个段独立计算此要求。 总结这些要求可以告诉我们 m 家商店是否足够。 

这将问题转化为对 L 的单调可行性检查，可以使用二分搜索来解决。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 顺序插入模拟| O((n + m) log n) | O((n + m) log n) | O(n) | 太慢而且没必要 |
 | 具有间隙可行性的二分搜索 | O(n log 1e9) | O(n log 1e9) | O(n) | 已接受 |

 ## 算法演练

 1、对现有店铺位置进行排序。 这确保了所有间隙都以有意义的顺序存在于连续元素之间，因为只有相邻的对才会影响答案。 
2. 计算连续商店之间的所有差距。 每个间隙都是一个独立的区间，可以接收新的存储。 
3. 定义一个函数来检查候选最大距离 L 是否可实现。 该函数确定需要多少额外存储才能确保间隙不超过 L。 
4. 对于每个长度为 g 的间隙，计算必须将其分成多少个段，以便每个段的长度最多为 L。所需的段数为 ceil(g / L)，这意味着我们需要 ceil(g / L) - 1 个新存储在该间隙内。 这是因为 k 个插入点创建了 k+1 个段。 
5. 对所有间隙所需的插入进行求和。 如果总数小于或等于m，则L是可行的。 
6. 对 L 从 1 到 10^9 进行二分查找。 对于每个中点，运行可行性检查。 如果可行，尝试较小的值； 否则增加L。 

二分搜索起作用的原因是可行性在 L 中是单调的。如果可以实现最大间隙 L，则也可以实现任何更大的值，因为它放松了约束并且永远不会增加所需插入的数量。 

### 为什么它有效

 一旦我们确定了目标最大段长度 L，每个间隙就会独立运行。分割单个间隙的贪婪方式始终是最佳的，因为将 k 点分布在除均匀之外的任何地方都不能将最大段长度减小到 ceil(g / (k+1)) 以下。 因此，可行性检查准确地捕获了每个间隙所需的最小插入数量。 由于这个要求是跨间隙的累加性和 L 中的单调性，二分搜索正确地识别出最小的可行最大距离。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def required_stores(g, L):
    if g <= L:
        return 0
    return (g - 1) // L

def can(L, gaps, m):
    need = 0
    for g in gaps:
        need += required_stores(g, L)
        if need > m:
            return False
    return True

n, m = map(int, input().split())
a = list(map(int, input().split()))
a.sort()

gaps = []
for i in range(n - 1):
    gaps.append(a[i + 1] - a[i])

lo, hi = 1, 10**9
ans = hi

while lo <= hi:
    mid = (lo + hi) // 2
    if can(mid, gaps, m):
        ans = mid
        hi = mid - 1
    else:
        lo = mid + 1

print(ans)
```排序步骤确保所有有意义的距离都被捕获为连续的差异。 可行性函数对每个间隙分割逻辑进行编码，其中每个间隙独立地贡献所需数量的插入存储。 表达式 (g - 1) // L 是无需浮点运算即可计算 ceil(g / L) - 1 的紧凑方法。 

二分搜索通过重复测试是否可以通过最多 m 次插入来全局强制执行建议的最大距离，从而缩小答案范围。

## 测试用例```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    gaps = [a[i+1] - a[i] for i in range(n - 1)]

    def need(g, L):
        if g <= L:
            return 0
        return (g - 1) // L

    def can(L):
        return sum(need(g, L) for g in gaps) <= m

    lo, hi = 1, 10**9
    ans = hi
    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1
    return str(ans)

 ## 边缘情况

 当由于 m 相对于主导间隙太小而无法进行有益的分裂时，就会出现一种边缘情况。 用于输入`0 1000000000`当 m = 0 时，算法产生大小为 10^9 的单个间隙，并且二分搜索立即收敛到该值，因为对于任何较小的 L，可行性检查都会失败。 

另一种情况是多个大间隙竞争有限的插入。 例如，如果间隙是`[100, 100, 100]`当 m = 1 时，可行性检查首先以二进制形式正确地将所有必需的插入归因于最大的缩减目标。 二分搜索确保我们永远不需要决定改进哪个差距； 相反，我们验证是否可以实现统一的界限。 

最后一个微妙的情况是 g 可以被 L 整除。公式`(g - 1) // L`确保精确的倍数不会超出所需的商店数量。 例如，如果 g = 10 且 L = 2，我们需要 4 个插入，生成大小恰好为 2 的段。这避免了朴素时可能发生的差一膨胀。`ceil(g / L) - 1`使用浮点运算的实现。
