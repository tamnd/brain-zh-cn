 ## 解决方案
 ## 问题理解

 我们有两个目标字符串，一个必须在第一个屏幕上结束，另一个必须在第二个屏幕上结束。 两个屏幕一开始都是空的。 每一秒，我们都可以将一个大写字母附加到一个选定的屏幕上，或者我们可以将一个屏幕的全部内容复制到另一个屏幕上，替换那里的任何内容。 

任务是达到最终配置，其中屏幕一等于字符串`s`并筛选两个等于字符串`t`，使用最少的操作次数。 

重要的细节是复制不是增量的，它总是覆盖整个目标。 这就产生了一个问题：决定何时“重用”一个屏幕上已经完成的工作，而不是在另一个屏幕上再次重建相同的前缀。 

约束很小，两个字符串的长度都为 100。这立即排除了超出多项式时间的大量优化的需要。 围绕 O(n^3) 或 O(n^2) 的解决方案是完全安全的，但问题的结构强烈表明存在基于共享前缀的更直接的 O(n^2) 或 O(n) 公式。 

当一个字符串为空或两个字符串相同时，就会出现一种微妙的边缘情况。 另一种情况是，最佳策略是首先完全构建一个字符串，然后在继续之前复制它，如果只考虑独立构建两个字符串，那么这一点并不明显。 

例如，如果`s = "A"`和`t = "ABCD"`，单独构建两者显然不是最佳选择； 相反，我们希望在创建共享结构后利用复制。 相反，如果`s`和`t`根本不共享前缀，复制几乎没有用。 

## 方法

 一种幼稚的方法是独立思考构建每个屏幕。 如果我们忽略复制，我们只需构建`s`在屏幕上一`|s|`步骤和`t`在屏幕上的两个`|t|`步数，总计`|s| + |t|`。 这始终有效，因为我们可以单独输入所有内容。 

然而，这忽略了复制操作。 关键的改进是意识到，当两个屏幕可以共享已经构建过一次的前缀时，复制就会变得有用。 

假设我们完全构造字符串`s`在屏幕一上。 我们可以随时将屏幕一复制到屏幕二，然后继续构建`t`从那时起。 如果我们在构建前缀后进行复制`s`，我们有效地“播种”第二个筛选，其候选前缀为`t`，如果该前缀与 的开头匹配，则可以减少重复的输入工作`t`。 

所以真正的问题是：有多少`t`可以与我们已经在第一屏上构建的东西相匹配，在一些前缀之后`s`已建成？ 由于我们只能复制整个屏幕，因此唯一有意义的状态是当屏幕一包含前缀时`s`第二个屏幕要么不包含任何内容，要么包含该前缀的副本。 

这导致了中心观察：唯一有用的同步点是两个屏幕共享公共前缀长度，并且该前缀同时是两个字符串的前缀。 之后，剩下的工作就是分别输入后缀了。 

最佳策略是选择一个分割点，我们决定以某个共同的前缀长度“同步”两个屏幕`k`。 我们建造`s`至少达到`k`，将其复制到第二个屏幕，然后独立于该共享状态完成两个字符串。 

这将问题简化为寻找最佳前缀长度`k`这样第一个`k`两个字符串的字符匹配（即最长的公共前缀）。 一旦我们有了这个，我们就可以计算成本：

 我们构建同步之前所需的较长前缀，然后复制一次，然后通过键入完成两个后缀。 

暴力版本将尝试所有可能的同步点并模拟操作，如果仔细实现状态转换，这将花费 O(n^3)。 只有前缀一致才重要的观察结果极大地破坏了搜索空间。

 ## 算法演练

 我们将问题重新定义为选择在两个屏幕之间复制共享结构的最佳时机。 

1.计算最长公共前缀长度`k`之间`s`和`t`。 这是可以在不发生冲突的情况下共享的最大初始字符数，因为任何不匹配都会破坏此时复制的有用性。 此步骤确定了复制实际上可以减少工作量的唯一区域。 
2. 考虑建立此共享前缀。 我们至少需要`k`由于我们从空开始，因此需要通过键入操作在一个屏幕上构造这些字符。 
3. 一旦第一个屏幕包含此前缀，请执行复制操作到第二个屏幕。 这可确保两个屏幕的长度对齐`k`。 
4. 从这一点来看，后缀`s`（从`k`向前）必须仅在屏幕一上键入，并且后缀`t`必须仅在屏幕二上输入。 这些操作是独立的，因为再次复制只会覆盖已经正确的前缀。 
5. 总成本变为`k`共享前缀的键入操作，加上一份副本，加上`(len(s) - k)`用于整理`s`，加上`(len(t) - k)`用于整理`t`。 

所以最终的答案是：`len(s) + len(t) - k + 1`。 

### 为什么它有效

 正确性取决于这样一个事实：任何有益的复制使用都必须源自两个屏幕包含相同内容的状态。 由于复制会完全覆盖，因此无法保留不是前缀的部分重叠。 因此，唯一可重用的结构是公共前缀。 任何试图在分歧点之前复制的策略都会立即引入不正确的字符，并且需要重新设计，这会影响任何潜在的收益。 这迫使所有最优策略等同于选择单个同步前缀长度。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()
    
    k = 0
    for i in range(min(len(s), len(t))):
        if s[i] == t[i]:
            k += 1
        else:
            break
    
    ans = len(s) + len(t) - k + 1
    print(ans)

if __name__ == "__main__":
    solve()
```该实现通过扫描两个字符串直到第一个不匹配来直接计算最长公共前缀。 这避免了任何动态编程或模拟。 

一个常见的陷阱是忘记单个复制操作成本，当两个字符串都非空时必须始终计算该成本。 另一个微妙之处是确保前缀比较在第一次不匹配时立即停止； 继续会错误地高估共享结构。

 ## 边缘情况

 对于相同的字符串，例如`s = t = "AAAA"`，算法发现`k = 4`，答案就变成了`4 + 4 - 4 + 1 = 5`。 这相当于输入字符串一次并复制一次，从而避免了重复工作。 

对于完全不同的字符串，例如`s = "A"`,`t = "B"`，我们得到`k = 0`，导致`1 + 1 + 1 = 3`。 最佳策略是使用一份副本独立键入两者，这实际上没有帮助，但仍然算作允许的操作。 

对于高度重叠的情况，例如`s = "ABCDE"`,`t = "ABCXY"`, 前缀`ABC`是共享的，因此只有后缀有所不同。 该算法正确地确保仅重用共享部分，并且分歧后的所有内容都独立重建，匹配通过覆盖复制语义强制执行的最小结构。
