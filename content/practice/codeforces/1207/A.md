 ## 解决方案
 ## 问题理解

 我们得到了一个小型餐厅模型，其中每个查询都描述了两种汉堡的可用成分和销售价格。 一个汉堡需要面包加牛肉，另一个汉堡需要面包加鸡肉。 每个汉堡恰好消耗两个面包，并且每种类型都消耗自己的成分。 

对于每个查询，我们必须决定生产多少个汉堡包和多少个鸡肉汉堡，以便尊重面包的总数，并使总收入最大化。 限制资源是包子、牛肉饼、鸡排，每次查询都是独立的。 

限制很小：每个数量最多 100 个，最多 100 个查询。 这意味着任何多达大约几百万次操作的解决方案对于满足时间限制来说都是微不足道的。 即使尝试汉堡的所有合理分布的方法也是可行的，但有一种更简单的结构可以完全避免枚举。 

这个问题中的一个天真的错误是假设我们应该始终优先考虑更昂贵的汉堡。 如果昂贵的汉堡消耗的资源限制性更大，那么这种说法并不总是正确的。 例如，如果小圆面包充足，但牛肉稀缺，而鸡肉丰富，那么优先考虑汉堡包可能会浪费本来可以用来制作更有价值的鸡肉汉堡的小圆面包。 

当两种汉堡类型的价格相同时，就会出现另一个微妙的边缘情况。 在这种情况下，任何尊重资源限制的分配都是最优的，但过度投入一种类型的贪婪策略可能会降低另一种类型的可行性，而不会提高利润。 

## 方法

 一种简单的暴力方法是尝试所有可能数量的汉堡包和鸡肉汉堡。 由于每个汉堡消耗两个面包，如果我们固定汉堡的数量，那么剩下的面包和配料决定了我们可以生产多少个鸡肉汉堡。 对于从零到最大可行值的每个汉堡数量选择，我们计算相应的鸡肉汉堡数量并评估利润。 这是正确的，因为它探索了两种汉堡类型之间面包的所有有效分布。 

问题在于，这仍然涉及每个查询迭代最多 100 个选择，然后在循环内计算约束。 虽然这已经足够小，但没有必要，因为问题的结构更简单：两个汉堡消耗相同的共享资源（面包），而其他成分是独立的约束。 关键的观察结果是，每种汉堡类型都可以被视为消耗有限的容量，唯一真正的耦合是面包约束。 

关键的见解是，面包是唯一的共享瓶颈。 每个汉堡正好消耗两个面包，因此汉堡的总数有以下界限：`b // 2`。 一旦我们决定生产一种类型的汉堡数量，其余的就可以分配给另一种类型，直至其成分限制。 由于只有两种类型，因此最佳策略减少为仅尝试两种有意义的配置：首先优先考虑汉堡包或首先优先考虑鸡肉汉堡。 这些贪婪的选择之一必须是最优的，因为将一种汉堡类型换成另一种类型仅取决于每个共享面包的边际利润，除此之外没有任何相互作用。 

这将问题简化为评估两个贪婪分配并取最大值。

 ## 算法演练

 我们通过测试两个可能的优先级来计算最佳利润。 

1. 首先计算如果我们按优先顺序排列汉堡包，我们可以制作多少个汉堡包。 这个受到牛肉和包子的限制，所以`min(p, b // 2)`。 这代表了对汉堡包在不违反限制的情况下最大程度的安全承诺。 
2.减去汉堡所用的面包，剩下`b - 2 * hamburgers`鸡肉汉堡的面包。 
3. 将鸡肉汉堡计算为`min(f, remaining_buns // 2)`。 这确保了我们不会超出鸡肉供应或面包的供应量。 
4. 计算总利润为`hamburgers * h + chicken_burgers * c`。 
5. 重复相同的过程，但颠倒优先顺序：首先最大化鸡肉汉堡，然后使用剩余的面包制作汉堡。 
6. 取两种策略之间利润最大的。 

我们显式测试两个方向的原因是贪婪决策取决于哪种汉堡类型首先访问共享面包资源。 

### 为什么它有效

 两种选择之间的唯一耦合是小圆面包约束，并且两种汉堡类型消耗的小圆面包相同。 这意味着任何解决方案都对应于分裂`b // 2`独立上限下两种类型之间的汉堡槽`p`和`f`。 利润与每种类型的汉堡数量呈线性关系，因此最佳解决方案必须处于极端分配状态，即首先尽可能多地填充一种类型，然后将剩余容量分配给另一种类型。 任何中间交换只能在两种类型之间移动单位，而不改变总包数，并且检查两个极端方向可保证捕获最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_one(b, p, f, h, c):
    buns = b // 2

    # case 1: prioritize hamburgers
    ham1 = min(p, buns)
    buns_left1 = buns - ham1
    chick1 = min(f, buns_left1)
    profit1 = ham1 * h + chick1 * c

    # case 2: prioritize chicken burgers
    chick2 = min(f, buns)
    buns_left2 = buns - chick2
    ham2 = min(p, buns_left2)
    profit2 = chick2 * c + ham2 * h

    return max(profit1, profit2)

t = int(input())
for _ in range(t):
    b, p, f = map(int, input().split())
    h, c = map(int, input().split())
    print(solve_one(b, p, f, h, c))
```该解决方案首先使用整数除以 2 将小圆面包减少为可用的汉堡槽，因为每个汉堡消耗两个小圆面包。 然后它显式地模拟这两种贪婪排序。 每次订购都会仔细考虑成分限制和剩余面包容量。 

唯一微妙的一点是确保我们在首先选择一种类型后始终重新计算剩余的面包。 忘记此步骤会导致过度计数和无效分配。

    return solve()

 ## 边缘情况

 一个最小的面包盒，比如`b = 1`立即将答案强制为零，因为无法形成汉堡。 该算法通过以下方式处理这个问题`b // 2`，它变为零，确保两种策略生产出零汉堡包和零鸡肉汉堡。 

例如，一种成分为零的情况`p = 0`，迫使所有生产都变成鸡肉汉堡。 在算法中，`min(p, buns)`正确地变为零，因此第一个策略自然地将所有容量分配给鸡，而不需要特殊处理。 

当两个汉堡价格相等时，该算法仍然有效，因为两个贪婪订单都会产生有效的分配。 由于利润是对称的，因此两种排序都会产生相同的结果，并且取最大值可以保持正确性，而不需要打破平局逻辑。
