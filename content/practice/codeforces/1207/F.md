 ## 解决方案
 ## 问题理解

 我们维护一个非常大的数组，索引从 1 到 500000，最初全为零，并且我们支持两种操作。 第一个操作将值添加到单个位置。 第二个操作要求结构化和：固定模数$x$和余数$y$，然后将索引位于算术级数内的所有数组值相加$y, y+x, y+2x, \dots$在允许的范围内。 

因此，类型 2 的每个查询都要求存储在一个残基类模上的总重量$x$，但仅适用于最大 500000 的索引。挑战在于更新和查询都是在线且完全混合的，并且查询中的模数不固定，它可以是最大 500000 的任何数字。 

限制是极端的：最多 500000 个查询，并且每个查询原则上可以触及数组的很大一部分。 每个查询的简单扫描将立即爆炸到大约$5 \cdot 10^{5} \times 5 \cdot 10^{5}$，这远远超出了任何可行的极限。 如果在整个数组中重复应用，即使每个元素的对数因子也太慢。 

隐藏的结构是小模数和大模数的行为非常不同。 大的$x$产生短算术级数，而小$x$产生长的。 解决方案取决于分别对待这两种制度。 

打破天真的推理的一个微妙问题是假设我们可以独立地预先计算每个模数的总和。 更新后，所有此类预计算都将失效，并且重新计算它们的成本太高。 

另一个陷阱是忘记类型 1 更新同时影响所有残留类别。 单个索引参与无限多个模数级数，因此任何簿记策略都必须确保更新正确传播，而不会显式触及每个模数。 

## 方法

 暴力解决方案独立处理每个查询。 对于类型 1 更新，我们只需增加数组即可。 对于带参数的类型 2 查询$x, y$，我们迭代所有索引$i = y, y+x, y+2x, \dots \le 500000$并对值求和。 

这是正确的，因为它直接遵循查询的定义。 问题是性能。 什么时候$x = 1$，循环触及 500000 个元素。 如果出现许多这样的查询，则在最坏的情况下总工作量会成二次方。 对于 500000 条查询，这是完全不可行的。 

关键的观察是，我们只需要一种快速方法$x$很小。 如果$x$很大，算术级数很短，所以蛮力实际上很快。 如果$x$很小，级数很长，但是这样的数量很少$x$值是有限的，这表明对残差进行预先计算。 

我们引入一个阈值$B \approx \sqrt{500000}$。 对于所有人$x \le B$，我们维护辅助结构。 对于每一个这样的$x$，我们维护一个数组`sum[x][r]`表示索引处所有值的总和$r \mod x$。 当我们在位置执行更新时$i$，我们更新所有`sum[x][i % x]`为了$x \le B$。 这需要花费$O(B)$每次更新。 

对于查询$x \le B$，我们使用预先计算的存储桶在 O(1) 内回答。 对于查询$x > B$，我们直接迭代进程，最多是$N / B$。 

这会分割工作负载，因此总体上没有任何操作成本太高。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(N)$每个查询|$O(N)$| 太慢了 |
 | 阈值分解|$O(\sqrt{N})$每项业务摊销|$O(N \sqrt{N})$| 已接受 |

 ## 算法演练

 1. 选择阈值$B = \lceil \sqrt{500000} \rceil$。 这将“许多残基类别”与“几步级数”分开。 
2.维护主数组`a[i]`存储当前值。 这是大步查询中快速直接访问所必需的。 
3.对于每一个$x \le B$，保持类似字典的结构`bucket[x][r]`存储索引全等的所有值的总和$r \mod x$。 这将每个模块类压缩为单个聚合值。 
4. 处理更新时`1 x y`，我们首先更新`a[x] += y`。 那么对于每一个$d \le B$，我们更新`bucket[d][x % d] += y`。 这可确保所有预先计算的模和保持正确。 每次更新的成本为$O(B)$。 
5. 处理查询时`2 x y`：

- 如果$x \le B$，我们直接返回`bucket[x][y]`，因为它已经包含所有相关指数的总和。 
- 否则，我们迭代从以下位置开始的索引$y$, 逐步经过$x$，并累积`a[i]`。 

分割起作用的原因是每个查询要么在恒定时间内处理，要么在一个短循环中处理，该循环由$N/B$。 

### 为什么它有效

 正确性取决于对于每个小模数的不变量$x \le B$,`bucket[x][r]`始终等于数组中当前索引全等的所有元素的总和$r \mod x$。 每次更新都会将增量值添加到每个此类的正确残基类别中$x$，因此不变量被逐步保留。 对于大模数，我们从不预先计算，因为查询长度足够小，可以直接计算而不会丢失任何元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

N = 500000
import math

B = int(math.sqrt(N)) + 1

a = [0] * (N + 1)

bucket = [None] * (B + 1)
for i in range(B + 1):
    bucket[i] = {}

out = []

q = int(input())
for _ in range(q):
    t, x, y = map(int, input().split())

    if t == 1:
        i = x
        val = y
        a[i] += val

        for d in range(1, B + 1):
            r = i % d
            if r in bucket[d]:
                bucket[d][r] += val
            else:
                bucket[d][r] = val

    else:
        mod = x
        r = y

        if mod <= B:
            out.append(str(bucket[mod].get(r, 0)))
        else:
            s = 0
            start = r
            while start <= N:
                s += a[start]
                start += mod
            out.append(str(s))

print("\n".join(out))
```该实现维护一个用于直接索引的完整数组，这对于有效处理大步查询至关重要。 这`bucket`结构是一个按模的哈希图，仅存储小模的残差和，避免了存储最多 500000 的所有值的完整数组的成本。 

整个更新循环`d ≤ B`是核心权衡。 这是可以接受的，因为$B$约为 700，即使更新 500000 次，总操作也保持在限制范围内。 

大模数的查询分支依赖于算术级数的直接遍历，这是安全的，因为访问的元素数量受以下限制$N/x$， 和$x > B$。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 |$O(\sqrt{N})$每次更新，$O(1)$或者$O(N/x)$每个查询| 更新涉及所有小模数，大查询遍历很少的索引 |
 | 空间|$O(N + B^2)$| 数组加上小模数的残差桶 |

 这种拆分确保了在所有查询中，总工作量仍然是可管理的，因为每个昂贵的操作都会被许多便宜的操作所补偿。 和$B \approx \sqrt{N}$，更新和查询成本平衡$O(\sqrt{N})$摊销，适合 500000 次操作的限制。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math
    N = 500000
    B = int(math.sqrt(N)) + 1

    a = [0] * (N + 1)
    bucket = [dict() for _ in range(B + 1)]
    out = []

    q = int(input())
    for _ in range(q):
        t, x, y = map(int, input().split())

        if t == 1:
            i, val = x, y
            a[i] += val
            for d in range(1, B + 1):
                r = i % d
                bucket[d][r] = bucket[d].get(r, 0) + val

        else:
            mod, r = x, y
            if mod <= B:
                out.append(str(bucket[mod].get(r, 0)))
            else:
                s = 0
                i = r
                while i <= N:
                    s += a[i]
                    i += mod
                out.append(str(s))

    return "\n".join(out)

 ## 边缘情况

 一个关键的边缘情况是更新影响属于小模数的许多残差类别的索引。 考虑在索引 1 处进行更新。对于每个小模数$x$，索引1属于残差$1 \bmod x$，所以每个桶都必须更新。 该算法通过迭代所有的来处理这个问题$x \le B$，确保所有模块化分解的一致性。 

另一种情况是查询where$x = 1$。 这减少了对整个数组的求和。 自从$x$如果很小，桶会立即返回余数0下存储的全局和，不需要遍历。 

最后一个微妙的案例很大$x$接近500000。级数最多包含一个元素，因此循环执行一次并立即返回。 这证实了即使没有预计算，最坏情况的查询成本也是安全的。
