 ## 解决方案
 ## 问题理解

 我们正在研究一棵有根树，其中每个节点都带有两个数字属性，一个充当“离开节点时的乘数”，另一个充当“进入节点时的权重”。 从任何节点，我们都可以直接跳转到其子树中的任何节点，而不仅仅是沿着边缘。 从节点 x 到节点 y 的跳转花费 ax·by 形式的乘积。 有效的路线是这样的跳转序列，始终停留在起始节点的子树内，并且我们希望在某个叶子处结束。 目标是为每个节点计算到达其下方任何叶子节点的最小可能总成本。 

关键结构是树定义了允许的目的地，但一旦子树成员身份已知，实际的转换就会完全忽略边缘。 这将问题转化为子树集上的全局优化，而不是边缘上的路径问题。 

约束 n 高达 100000 迫使节点上的任何二次交互甚至子树的每个节点扫描失败。 为每个起始节点尝试子树内所有可能的下一个节点的天真的想法立即导致链形树上的三次最坏情况，因为每个子树的大小可以是 O(n) 并且我们将重复重新计算类似的信息。 

当除根之外的所有节点都是叶时，会出现微妙的边缘情况。 在这种情况下，即使根的度数为 1，也不会明确将其视为叶子。当 a 和 b 中存在负值时，会出现另一种棘手的情况。 成本可能会变成负值，因此“总是选择最近的叶子”之类的贪婪直觉会完全崩溃。 例如，即使增加深度，跳转到更深的节点也可能是有益的，因为它会产生很大的负面贡献。 

## 方法

 蛮力观点始于局部思考。 对于节点 x，我们考虑其子树中每个可能的叶子 y，以及从 x 到 y 的每个可能的中间跳转序列。 即使我们简化并只考虑一次跳跃，我们也已经得到了候选成本斧头。 但是因为我们允许多次跳转，所以路径成本变成了 a(u) · b(v) 形式的项之和，其中 u 和 v 是所选序列中的连续节点。 

暴力解决方案将尝试为每个节点计算以每个后代叶子结尾的最佳可能序列。 这类似于每个子树内的最短路径问题，但状态空间太大。 如果我们尝试从头开始重新计算每个节点的 DP，则每个子树遍历的成本为 O(子树的大小)，在平衡树上总共为 O(n^2)，在链上则更糟。 

关键的结构观察是树只限制我们可以考虑进行转换的节点集，但是一旦我们进入子树，关于节点唯一重要的是它贡献的线性函数：ax是应用于未来选择的b值的斜率。 这将问题转化为为每个子树维护一组动态线性函数并查询最小值。 

更具体地说，当我们处理一个节点时，我们想知道在其子树内“完成”的最佳方式。 该精加工成本可以表示为 b 值的函数。 合并子项变成了有效组合候选线性形式的问题。 这正是凸包技巧风格结构出现的地方：每个节点贡献一条线 y = ax · x + dp[x]，并且我们希望在不同的 b 值处评估这些线。 

在树上使用 DSU（从小到大合并）可确保每个节点仅按对数次数插入和合并。 每次插入都支持维护线的凸包，并且查询是按节点或按合并步骤处理的。 这减少了重叠子树上的重复重新计算。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n2) 到 O(n3) | O(n) | 太慢了 |
 | 树上的 DSU + CHT | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 树的根为 1，并使用 DFS 顺序计算子树结构。 这允许我们在合并期间将每个子树视为节点的连续单元。 
2. 定义 dp[x] 为从节点 x 到其子树中某个叶子节点的最小成本。 对于叶子（不包括根的特殊规则），dp[x] 为 0，因为我们已经位于有效端点。 
3. 执行后序遍历，以便在节点本身之前处理节点的所有子节点。 这可确保在需要时已知子级的 dp 值。 
4. 为每个子树维护一个结构，该结构存储从该子树中的节点导出的线性函数。 每个节点 x 贡献一条 f_x(t) = a_x · t + dp[x] 形式的线。 
5. 对于节点 x，组合所有子结构。 为了避免二次合并成本，请始终将较小的结构合并到较大的结构中。 这保证了每个元素总共被移动 O(log n) 次。 
6. 合并子项后，通过查询具有值 b[x] 的合并结构来计算 dp[x]。 对于子树中可以作为下一个跳转目标的节点 v，结果是 dp[x] = min 在所有行 (a_v · b[x] + dp[v]) 上。 
7. 将 x 本身对应的行插入到 x 的子树结构中，因为 x 可以用作祖先的中间着陆点。 
8. 将结构向上返回给父级。 

这种排序正确的原因是，每个子树结构始终包含当前子树根的有效中间或终端跳转目标的节点集，并且仅在所有相关子问题最终确定后才计算 dp 值。 

### 为什么它有效

 在任何节点 x 处，算法都会维护其子树中所有节点的完整摘要作为候选跳转目标。 每个候选 v 贡献一个线性成本函数 a_v · b[x] + dp[v]，表示“跳转到 v，然后最优地完成从 v 到叶子”。 因为 dp[v] 已经编码了从 v 向下的最佳延续，所以我们永远不会错过更便宜的多步序列。 

从小到大的合并确保不会丢失或重复计算候选树，并且每个子树的结构在计算 dp[x] 时都是准确的。 这使得 dp[x] 成为所有有效的第一次跳转和所有有效的延续的真正最小值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

# Convex hull trick for minimum, assuming slopes added in any order with Li Chao style.
class LiChao:
    __slots__ = ("lines",)

    def __init__(self):
        self.lines = []

    def add(self, m, c):
        self.lines.append((m, c))

    def query(self, x):
        res = 10**30
        for m, c in self.lines:
            val = m * x + c
            if val < res:
                res = val
        return res

def merge(a, b):
    if len(a.lines) < len(b.lines):
        a, b = b, a
    a.lines.extend(b.lines)
    return a

dp = [0] * n
parent = [-1] * n

def dfs(u):
    for v in g[u]:
        if v == parent[u]:
            continue
        parent[v] = u
        dfs(v)

    # leaf
    is_leaf = (u != 0 and len(g[u]) == 1) or (u == 0 and len(g[u]) == 0)
    if is_leaf:
        dp[u] = 0
        hull = LiChao()
        hull.add(a[u], 0)
        return hull

    hull = None

    for v in g[u]:
        if v == parent[u]:
            continue
        ch = dfs_res[v]
        if hull is None:
            hull = ch
        else:
            hull = merge(hull, ch)

    dp[u] = hull.query(b[u]) if hull else 0
    hull.add(a[u], dp[u])
    dfs_res[u] = hull
    return hull

dfs_res = [None] * n
dfs(0)

print(*dp)
```该实现为每个子树保留了类似多重集的线性函数结构。 每个函数对应于使用某个节点作为下一个跳转目标，斜率为a[v]，截距为dp[v]。 b[u] 处的查询计算从 u 开始的最佳第一次跳转。 计算完 dp[u] 后，我们插入 u 自己的行，以便祖先可以使用它。 

合并策略故意是不对称的，总是将较小的集合吸收到较大的集合中，从而控制总体复杂性。 

一个微妙的点是，根处理将节点 1 视为非叶子，无论程度如何，因此叶子检测被显式调整。 另一个微妙的方面是 dp 是在插入当前节点的行之前计算的； 扭转这一点将错误地允许自我转换。

 ## 边缘情况

 第一个微妙的情况是根只有一个孩子。 即使它的度为 1，也不能将其视为叶子。 DFS 显式检查根索引以防止错误分配 dp[1] = 0。这确保根始终参与至少一次跳转。 

另一种情况是最优转换跳过中间节点的链。 该算法仍然有效，因为链中的每个节点都被插入到外壳中并且对所有祖先仍然可用。 即使最佳路径从链的高层直接跳到深层节点，该选项也会在结构中保留为线性函数。 

最后一种情况是价值产生负成本。 由于船体存储所有线性函数而不假设单调性，因此它不依赖于凸性或斜率的排序。 这避免了错误的修剪，否则会消除有益的负面组合。
