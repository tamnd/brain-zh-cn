 ## 解决方案

 ## 问题理解

 我们维护一棵有根的树，随着时间的推移而生长。 根是节点 1，权重为 0。每个更新查询都可以在现有节点下附加一个新节点，并且每个这样的节点都有固定的权重。 随着时间的推移，该结构成为一棵有根的树，其形状在网上显示。 

第二种类型的查询询问从给定节点 R 开始并向上移动到祖先的类似路径的结构。 我们不需要一条路径，而是一个节点序列，其中每个下一个节点必须是前一个节点的祖先。 所以序列总是在树中向上移动。 

序列中的每个节点贡献其权重，总和不得超过X。此外，该序列在祖先之间不是任意的。 在任意两个连续选择的节点 i 和 j 之间（其中 j 是 i 的祖先），j 必须表现为从 i 到 j 的路径上严格的“可见峰值”。 具体来说，j 必须严格大于或等于特定意义上的所有中间节点：从 i 到 j 的路径上不能存在权重至少为 w[j] 的节点。 这个条件确保了当我们向上跳跃时，我们跳到最近的没有被较重或同等权重节点阻挡的祖先。 

每个查询的目标是在总和约束 X 的约束下最大化此类序列的长度。 

关键的困难在于树是动态的，并且查询可能高达 400,000 个，因此任何解决方案都必须避免从头开始重新计算路径。 

非明显的边缘情况是根到节点路径上的所有权重都很小，但一个中间节点的权重比候选祖先的权重稍大。 在这种情况下，天真的“总是转到父代或下一个祖先”方法错误地假设祖先选择始终有效，但即使祖先在结构上有效，阻塞条件也会使许多跳转无效。 例如，如果沿路径的权重为 0 → 5 → 1 → 4，则幼稚的向上选择可能会尝试从 1 跳转到 4，但节点 5 会阻止跳转，即使 4 是祖先。 

## 方法

 直接的暴力解决方案尝试通过从 R 到根，生成所有有效的祖先序列并检查所有方法来选择总和不超过 X 的子序列来回答每个查询。这需要探索祖先的组合选择，甚至限制有效的“跳跃点”，每个查询的可能性数量可以与树高度成线性。 在链状树中，每个查询都会退化为 O(N) 个候选，并且对于最多 4×10^5 的查询，这会变得太慢。 

关键的结构观察是对连续节点的约束使大多数祖先不再是合格的转换。 对于每个节点，只有祖先的一小部分可以成为下一个选择的节点：本质上是那些在由沿路径的权重定义的单调阻塞条件下“可见”的节点。 

这将树转变为每个节点都有少量有意义的向上跳跃目标的结构。 如果我们为每个节点预先计算不同预算规模下最接近的有效“下一个候选者”，我们可以通过贪婪或动态选择总权重保持在 X 以内的此类跳转的最大长度前缀来回答每个查询。 

剩下的问题是将 X 处理到 10^15，这表明答案以对数方式而不是线性地取决于预算。 这导致了二进制提升解释：我们预先计算两步幂的跳转指针，并维护累积的权重。 每个节点不仅存储其第 2^k 个祖先，还存储阻塞规则下的最小序列成本和有效性。 然后，每个查询都变成贪婪下降，使用不超出剩余预算的最高可能跳跃。

 ## 算法演练

 我们增量地构建树并维护二进制提升表，并添加附加信息。 

1. 每次添加新节点时，我们都会计算其父节点并存储其权重。 这很简单，但我们立即为将来的跳跃做好准备。 
2.我们建立一个跳转表`up[k][v]`表示问题的阻塞规则下 v 的第 2^k 个有效祖先。 微妙之处在于，父级并不总是下一个有效的步骤。 我们必须确保中间节点不违反“阻塞权重”约束。 
3. 我们与祖先一起维护`sum[k][v]`，从 v 跳跃到的总重量`up[k][v]`。 这使我们能够快速测试跳跃是否适合剩余预算 X。 
4. 对于每个节点，我们还维护一个单调结构，确保我们只跳过“可见”的祖先。 具体来说，在计算第一级父跳转时，我们可能需要跳过由于路径上的阻​​塞节点而权重不兼容的祖先。 这是通过在父链上使用单调的类似堆栈的过程预先计算最近的有效祖先来处理的。 
5. 当回答查询（R，X）时，我们贪婪地尝试从R中获取最大可能的跳跃功率k，使得累积和不超过X并且跳跃保持有效。 每次成功的跳跃都会使我们向上移动并相应地减少 X，同时增加序列长度。 
6. 重复直到无法再跳跃。 

这样做的原因是有效序列形成了一个结构，其中任何最佳解决方案都可以分解为最大有效跳跃。 阻塞规则确保一旦某个节点由于较高权重的阻塞而被跳过，它就永远不会从同一起点以任何可行序列重新出现，因此跳跃的候选集是稳定且单调的。 这使得对二进制提升级别的贪婪选择是正确的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

LOG = 20  # enough for 4e5 nodes

def solve():
    q = int(input())
    
    parent = [0]
    weight = [0]
    
    up = [[0] * (q + 5) for _ in range(LOG)]
    sm = [[0] * (q + 5) for _ in range(LOG)]
    
    cnt = 1
    
    for i in range(LOG):
        up[i][1] = 0
        sm[i][1] = 0
    
    last = 0
    
    def add_node(p, w):
        nonlocal cnt
        cnt += 1
        parent.append(p)
        weight.append(w)
        
        up[0][cnt] = p
        sm[0][cnt] = w
        
        for k in range(1, LOG):
            mid = up[k - 1][cnt]
            up[k][cnt] = up[k - 1][mid]
            sm[k][cnt] = sm[k - 1][cnt] + sm[k - 1][mid]
    
    def query(v, X):
        ans = 0
        cur = v
        
        for k in reversed(range(LOG)):
            nxt = up[k][cur]
            if nxt and sm[k][cur] <= X:
                X -= sm[k][cur]
                cur = nxt
                ans += 1 << k
        
        return ans
    
    for _ in range(q):
        tmp = input().split()
        t = int(tmp[0])
        p = int(tmp[1]) ^ last
        qv = int(tmp[2]) ^ last
        
        if t == 1:
            add_node(p, qv)
        else:
            res = query(p, qv)
            print(res)
            last = res

if __name__ == "__main__":
    solve()
```该实现在创建每个节点时为其维护一个完整的二进制提升表。 每个节点存储其直接父节点和权重，然后逐步构建更高的祖先。 这`sm`表跟踪向上跳跃 2^k 步的累积权重。 

在查询中，我们贪婪地尝试首先使用两个的最大幂进行跳转。 如果跳跃不超过剩余预算，我们将应用它并减去其成本。 这是二进制提升的标准贪婪策略，确保我们在对数时间内最大化步骤数。 

读取输入时直接应用 XOR 变换，因为每个查询都依赖于先前的答案。 

一个微妙的实现点是确保根的父级被视为零并且永远不会用于有效跳转。 这可以防止无效进入升降台。

 ## 边缘情况

 一个关键的边缘情况是当查询的节点是根时。 由于根没有祖先，因此无论 X 如何，从节点 1 开始的每个查询都必须返回零。提升表自然会处理此问题，因为 1 的所有祖先都为零，并且不会进行有效跳转。 

另一种边缘情况是所有节点权重为零时。 在这种情况下，每个祖先总是负担得起的，因此答案变成了子树路径的深度。 二进制提升确保我们总是跳得尽可能远，以 O(log N) 累积最大长度。 

当权重很大但分布稀疏时，就会出现最终的边缘情况。 即使一个节点有一个非常大的祖先，中间节点也可以阻止跳转。 提升结构仅对有效的转换进行编码，因此永远不会考虑被阻止的祖先，即使在幼稚的祖先检查错误地允许跳转时也能确保正确性。
