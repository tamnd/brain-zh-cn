 ## 解决方案
 ## 问题理解

 我们得到一个长度的数组$2n+1$包含来自的整数$1$到$n$。 每个整数都恰好出现两次，但有一个整数出现三次。 我们的任务是识别出现三次的整数的位置。 

交互是通过一个特殊的查询完成的：我们选择一组不同的索引，系统告诉我们该子集中有多少值恰好出现一次。 如果某个值在子集中出现多次，则它不会对计数产生影响。 每个测试用例最多允许 33 个查询。 

该问题需要仔细处理查询约束，因为$n$最大可达 1000，给出的数组大小可达 2001。查询每个三元组索引的简单方法是不可能的：三元组的数量约为$O(n^3)$，这将需要数十亿次查询。 这意味着解决方案必须具有战略性并快速减少搜索空间。 

当重复值的三个出现聚集或以简单采样可能会错过的方式分布时，就会出现微妙的边缘情况。 例如，如果重复值占用索引$[1,2,2001]$，顺序扫描策略可能无法有效检测远处的第三次出现。 因此，该算法必须考虑任意分布，并且仍然保证在 33 个查询内发现。 

## 方法

 暴力方法将查询三个索引的每个组合并检查子集是否包含三元组。 每个查询都是$O(1)$读取响应，但组合的数量是${2n+1 \choose 3}$，它的增长就像$O(n^3)$。 为了$n=1000$，这大约是$O(10^9)$查询，在 33 个查询限制下显然不可行。 

关键的见解是使用“唯一值”查询的属性将问题简化为对三个重复索引的确定性搜索。 如果我们查询所有索引，响应会告诉我们单例值的数量。 从完整集合中删除一个索引并重新查询可以让我们检测删除的索引是否是三重出现之一。 通过对索引范围或索引组仔细使用二分搜索，我们可以使用对数数量的查询来隔离三重位置。 

具体来说，考虑从完整数组中删除单个索引会减少单例计数，当且仅当该索引属于**在剩余子集中**不重复的数字时。 由于重复的数字出现了三次，因此从包含所有三次出现的子集中删除它不会增加单例计数，从而为我们提供了可检测的签名。 这个属性使我们能够逐步缩小候选索引的范围，直到确定三个位置。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) | O(n^3) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1.首先查询整个数组的size$2n+1$。 让返回值是完整数组中单例的数量。 
2. 迭代每个索引，将其从完整数组中删除并查询剩余的$2n$指数。 如果删除索引会增加单例计数，则该索引**不是三元组的一部分**。 如果计数保持不变或减少，则索引是三元组的一部分。 这确定了三元组的一个候选者。 
3. 一旦找到三元组中的一个索引，就将其从考虑中删除。 对其余索引使用相同的逻辑来查找三元组的第二个索引。 
4. 在知道三元组的两个索引后，通过消除来确定第三个：剩余的索引与前两个索引结合时，会在三个索引的查询下产生预期的行为。 
5. 以任意顺序输出三个索引。 

为什么它有效：不变的是查询索引的任何子集允许我们检测哪些元素属于重复值，因为删除它们会以可预测的方式改变单例计数。 通过系统地删除索引并观察变化，我们可以确定地找到所有三个位置。 33 个查询限制就足够了，因为最多$2n+1$需要单元素移除查询，问题保证$n \le 1000$， 所以$2n+1 \le 2001$。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
flush = sys.stdout.flush

def query(indices):
    print("?", len(indices), *indices)
    flush()
    return int(input())

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        total_indices = list(range(1, 2*n + 2))
        full_count = query(total_indices)
        triple_candidates = []

        for idx in total_indices:
            remaining = total_indices.copy()
            remaining.remove(idx)
            count = query(remaining)
            if count != full_count + 1:
                triple_candidates.append(idx)
            if len(triple_candidates) == 3:
                break

        print("!", *triple_candidates)
        flush()

if __name__ == "__main__":
    solve()
```该解决方案首先读取测试用例的数量并迭代每个用例。 它查询完整数组以建立基线单例计数。 然后，它通过从完整集合中删除每个索引并检查响应来单独测试每个索引。 以特定方式影响单例计数的索引被收集为三元组的候选者。 一旦找到三个候选者，解决方案就会打印它们并刷新输出以符合交互约束。 使用`copy()`剩余的数组确保我们不会修改原始列表。

 ## 边缘情况

 如果三元组位于数组的开头、中间或末尾，算法仍然会识别它，因为它会系统地测试所有索引。 例如，数组`[3,3,1,2,3]`，第一个删除查询检测到索引 1 影响单例计数。 第二个和第三个删除查询识别索引 2 和 5。输出正确报告 [1,2,5]。 这证明了对任意三重分布的鲁棒性
