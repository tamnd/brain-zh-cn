 ## 解决方案
 ## 问题理解

 我们需要构造一个数组$a_0, a_1, \dots, a_n$开始于$a_0 = 0$。 

对于下一个位置，我们只有两种选择。 我们可以通过以下方式增加当前值$x$，或减少$y$。 唯一的限制是序列中的每个值最多只能保留$B$。 负值是完全允许的。 

在所有有效序列中，我们希望元素总和尽可能大。 

约束足够小，我们可以单独处理每个位置。 虽然$t$可以大到$10^4$，所有的总和$n$值最多是$2 \cdot 10^5$。 这意味着$O(n)$每个测试用例的算法，或更准确地说$O(\sum n)$在所有测试用例中，很容易在时间限制内完成。 对所有可能的选择进行指数探索是不可能的，因为每个位置都有两个选择，导致$2^n$序列。 

棘手的部分是认识到最大化总和不是需要动态规划的全局优化问题。 结构要简单得多。 

考虑这个输入：```
1
4 1 7 3
```正确的顺序是：```
0, -3, -6, 1, -2
```与总和$-10$。 

总是试图添加的粗心策略$x$会立即违反界限，因为$0 + 7 > 1$。 由于允许值变为负数，因此最优解可能会故意先向下移动，然后才向上移动。 

另一个有趣的案例是：```
1
3 5 5 1
```最优的顺序是：```
0, 5, 4, 3
```与总和$12$。 

到达后$5$，添加另一个$5$会超过$B$，所以我们必须减去$1$。 盲目地交替运算或在达到限制后总是选择减法的解决方案将错过最佳总数。 

大的答案也是可能的：```
1
7 1000000000 1000000000 1000000000
```答案是：```
4000000000
```使用 32 位整数会溢出。 实现必须使用 Python 整数或其他语言中的 64 位算术。 

## 方法

 最直接的方法是将每个位置视为二元选择。 在步骤$i$，或者添加$x$或减去$y$。 每当它们产生有效值时，我们就可以递归地尝试这两种可能性并保持最佳总和。 

这种强力搜索是正确的，因为它检查每个有效序列。 不幸的是，它有$2^n$最坏情况下的状态。 和$n$最多$2 \cdot 10^5$，这是完全不可行的。 

关键的观察结果是目标是最大化所有序列值的总和。 每一步，未来只取决于当前的价值。 如果允许两种操作，则选择较大的结果值总是更好。 

假设当前值为$cur$。 

如果$cur + x \le B$，那么两个候选的下一个值是：$$cur + x$$和$$cur - y$$自从$x > 0$和$y > 0$,$$cur + x > cur - y.$$更大的下一个值不仅增加了当前对答案的贡献，还为所有未来的决策提供了更大的起点。 当加法有效时，永远没有理由选择减法。 

这意味着这个决定是被迫的：

 如果添加$x$保持在限度之内，就去做。 

否则，减去$y$。 

这产生了一个简单的贪婪模拟。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n)$|$O(n)$| 太慢了 |
 | 最优贪心模拟 |$O(n)$|$O(1)$| 已接受 |

 ## 算法演练

 1. 将当前值初始化为$cur = 0$。 
2. 将答案初始化为$ans = 0$， 自从$a_0 = 0$贡献总和。 
3. 对于每个位置$1$到$n$,检查是否添加$x$会将值保持在允许的范围内。 
4.如果$cur + x \le B$， 放$cur = cur + x$。 

这是最好的选择，因为它产生的值严格大于$cur - y$。 
5. 否则，设置$cur = cur - y$。 

在这种情况下，加法是被禁止的，因此减法是唯一有效的移动。 
6. 添加新值$cur$到运行总计。 
7.全部处理完毕后$n$位置，输出累加和。 

### 为什么它有效

 贪心选择是局部和全局最优的。 

每当$cur + x \le B$，这两种操作都是合法的。 加法后的结果总是大于减法后的结果，因为$x$和$y$是积极的。 

选择较大的值会立即增加总和中的当前项。 它还为我们未来的步骤留下了更大的当前值。 选择后可获得任意顺序$cur - y$可以从更大的状态复制$cur + x$具有同等或更好的未来贡献。 

因此，每次加法可用时，它都会支配减法。 我们唯一做减法的时候是加法违反约束的时候。 每一步重复此规则都会产生最大可能的总和。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    answers = []

    for _ in range(t):
        n, B, x, y = map(int, input().split())

        cur = 0
        total = 0

        for _ in range(n):
            if cur + x <= B:
                cur += x
            else:
                cur -= y

            total += cur

        answers.append(str(total))

    sys.stdout.write("\n".join(answers))

solve()
```变量`cur`存储当前序列值。 我们开始于`0`，对应于$a_0$。 

对于每个新位置，我们首先检查是否添加$x$保持在上限之内$B$。 如果确实如此，我们就会采取该选择。 否则我们必须减去$y$。 

确定新值后，我们立即将其添加到`total`。 自从`total`从零开始并且$a_0 = 0$，第一个元素不需要单独处理。 

一个常见的错误是认为负值是被禁止的。 该问题仅限制上面的值，因此减法可以产生任意负数。 

另一个常见错误是使用 32 位整数。 样本本身包含一个答案$4 \times 10^9$，超出了有符号的 32 位范围。 Python 会自动处理这个问题。

 ## 边缘情况

 ### 加法恰好达到界限

 输入：```
1
2 5 5 1
```痕迹：```
0 -> 5 -> 4
```第一步使用加法，因为$0 + 5 = 5$，这仍然有效。 一些不正确的实现使用严格的不等式并拒绝这一举动。 所得总和为：```
0 + 5 + 4 = 9
```### 允许负值

 输入：```
1
3 1 5 3
```痕迹：```
0 -> -3 -> -6 -> -1
```第一次添加将超过$B$，因此必须进行减法。 该算法正确地允许序列低于零，因为该问题没有施加下限。 最终总和为：```
0 + (-3) + (-6) + (-1) = -8
```### 超过 32 位范围的大答案

 输入：```
1
7 1000000000 1000000000 1000000000
```痕迹：```
0 -> 10^9 -> 0 -> 10^9 -> 0 -> 10^9 -> 0 -> 10^9
```答案是：```
4000000000
```任何使用 32 位有符号整数的实现都会溢出。 贪心算法本身仍然是正确的，但数据类型必须足够大才能存储累加和。
