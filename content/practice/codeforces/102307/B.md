 ## 解决方案
 ## 问题理解

 我们有一个非空字符串`s`。 唯一允许的操作是将字符附加到其右端。 目标是附加尽可能少的字符，以便整个结果字符串成为回文。 

关键的限制是我们不能修改或删除任何已经存在的字符。 假设一些后缀`s`已经是一个回文。 如果我们将该后缀保留为最终回文的中心部分，则它之前的所有内容都可以通过附加其相反内容来镜像。 例如，对于`helloworld`，最长的回文后缀就是`d`。 前面的前缀是`helloworl`，其逆序是`lrowolleh`，所以答案就变成了`helloworldlrowolleh`。 

输入长度最多为 5000。这足够小`O(n^2)`该算法具有潜在的实用性，但它也使线性解决方案变得简单，并且无需依赖 Python 字符串操作的相对慷慨的常数因子。 一个`O(n^3)`这种方法显然不合适，因为 5000 个字符已经意味着数十亿次操作。 目标解决方案将使用`O(n)`时间和`O(n)`记忆。 

有几种边界情况可能会使原本合理的实现变得错误。 对于单字符输入，例如`a`，字符串已经是回文，所以正确的输出是`a`。 始终附加至少一个字符的实现会错误地生成更长的字符串。 

对于已经是回文的字符串，例如`anitalavalatina`，不应附加任何内容。 正确的输出是`anitalavalatina`。 仅搜索正确的回文后缀的实现可能会意外地附加不必要的字符。 

后缀不必只有一个字符。 为了`aace`，最长的回文后缀是`e`，所以答案是`aacecaa`。 一种粗心的方法，仅检查整个字符串是否是回文，否则附加整个反向字符串，会产生`aaceecaa`，这是有效的但不是最小的。 

最长的回文后缀也可以很长，但不是整个字符串。 为了`abac`, 后缀`c`是唯一比一个字符长的回文后缀，所以答案是`abacaba`。 该算法必须找到最长的此类后缀，而不是简单地停在第一个方便的回文上，除非以正确的顺序检查候选者。 

## 方法

 直接的方法是从整个字符串开始尝试每个后缀，并检查该后缀是否是回文。 找到的第一个回文后缀是最长的。 如果它的长度是`k`, 长度前缀`n-k`不是该后缀的一部分，因此我们添加其反向内容。 这是正确的，因为现有后缀已经是对称的，而前缀中的每个字符都需要在右侧添加匹配字符。 

回文检查后缀的长度`k`最多需要`floor(k/2)`人物比较。 如果每个候选都必须被检查并且每次检查都达到中点，则比较的总数为`sum(floor(k/2))`为了`k = 1 ... n`。 

为了`n = 5000`，这正是`6,250,000`比较。 创建和反转候选子串还引入了额外的`O(n^2)`字符复制。 因此，在最坏的情况下，该方法是二次的。 有了这个特定的界限，它就可以在多种语言中通过，但它并没有利用问题的结构。 

更快的观察是，找到最长的回文后缀可以转换为标准的前缀匹配问题。 反转字符串并调用它`r`。 后缀为`s`正是当相应的前缀`r`是同一个字符串。 

例如，考虑`s = abac`。 它的逆向是`r = caba`。 后缀`c`的`s`对应前缀`c`的`r`。 如果更长的后缀`s`是回文的，较长的前缀`r`将匹配后缀`s`本身。 

我们可以使用 KMP 前缀函数对此比较进行编码。 构造`r + '#' + s`。 

分隔符是输入中不会出现的字符，因此前缀不会意外地与`r`进入`s`。 KMP前缀函数的最终值给出了最长前缀的长度`r`这也是一个后缀`s`。 因为前缀为`r`是后缀的反转`s`，它们之间的相等意味着该后缀在两个方向上读起来相同。 这正是我们需要的最长的回文后缀。 

一旦知道了这个长度，剩下的事情就迎刃而解了。 如果最长的回文后缀有长度`k`, 追加`reverse(s[:n-k])`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | n ≤ 5000 时接受，但效率较低 |
 | KMP 前缀功能 | O(n) | O(n) | 已被接受且最佳 |

 ## 算法演练

 1.读取字符串`s`并构造其逆向`r`。 我们对回文后缀感兴趣`s`，当从相反的方向看时，它们成为前缀。 
2. 构建组合字符串`t = r + '#' + s`。 分隔符不得出现在`s`，因为 KMP 前缀函数绝不能将分隔符两侧的字符视为候选匹配的一部分。 
3. 计算KMP前缀函数`pi`为了`t`。 对于每一个职位，`pi[i]`存储最长的适当前缀的长度`t`这也是一个以position结尾的后缀`i`。 
4. 采取`k = pi[-1]`。 这是最长的前缀`r`这也是一个后缀`s`。 由于前缀为`r`是相应后缀的反转`s`，相等意味着这个后缀是回文。 
5. 保留第一`n-k`的字符`s`作为仍然需要镜像的部分。 附加他们的相反，`s[:n-k][::-1]`。 生成的字符串是回文字符串。 
6. 打印结果字符串。 如果`s`已经是回文了，那么`k = n`， 所以`s[:n-k]`是空的并且没有附加任何内容。 

### 为什么它有效

 让`P`是最长的回文后缀`s`，长度`k`。 因为`P`是一个回文，它的反转仍然是`P`。 反转整个字符串会将此后缀变成前缀`r`， 所以`P`同时是一个前缀`r`和后缀`s`。 KMP 前缀函数找到最长的重叠，准确给出`k`。 

剩余前缀`s[:n-k]`放置在最终字符串的开头。 附加其反向会在相反的一侧提供匹配的字符，而中间部分`P`已经是一个回文。 因此构造的字符串是一个回文。 

最小性来自于选择最长的回文后缀。 任何有效的最终回文都必须保留原始字符串的一些后缀作为其中心回文部分，因为只有新字符可以添加到右侧。 使用较短的回文后缀会留下更多的原始字符进行镜像，并且需要更多的插入。 因此，最长的回文后缀给出了尽可能少的附加字符数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve_string(s):
    r = s[::-1]
    t = r + '#' + s

    pi = [0] * len(t)

    for i in range(1, len(t)):
        j = pi[i - 1]

        while j > 0 and t[i] != t[j]:
            j = pi[j - 1]

        if t[i] == t[j]:
            j += 1

        pi[i] = j

    k = pi[-1]
    return s + s[:len(s) - k][::-1]

def main():
    s = input().strip()
    print(solve_string(s))

if __name__ == "__main__":
    main()
```这`solve_string`函数首先创建`r`，输入的相反。 组合后的字符串`t`包含 KMP 比较前缀所需的信息`r`后缀为`s`。 

前缀数组`pi`以标准方式计算。 变量`j`表示当前候选匹配​​的长度。 什么时候`t[i]`不匹配`t[j]`， 下列的`pi[j - 1]`直接跳转到下一个可能的边界，而不是从零重新开始比较。 这就是前缀计算线性化的原因。 

最终值`pi[-1]`是最长回文后缀的长度。 如果`k`是长度，必须附加的字符数是`len(s) - k`。 Python 切片生成所需的前缀`s[:len(s) - k]`， 和`[::-1]`准确提供右侧所需的字符。 

分隔符`#`是安全的，因为问题的输入是一个不带空格的字符串，但该语句没有显式地将字母表限制为小写字母。 更具防御性的实现可以选择输入中不存在的分隔符。 上面的代码假设了此问题的常用字符集。 为了使实现完全独立于字母表，可以使用短循环来选择分隔符。 

不存在整数溢出问题，因为 Python 整数是任意精度的，并且涉及的唯一索引受字符串长度限制。

 ## 边缘情况

 对于单字符输入`a`，反转后的字符串也是`a`。 最长的前缀后缀匹配有长度`1`， 所以`k = n`。 前缀`s[:0]`为空，算法返回`a`不添加任何东西。 

对于已经是回文的输入，例如`anitalavalatina`，反转后的字符串与原始字符串相同。 KMP发现全长重叠，所以`k = n`。 这使得附加的前缀为空，并防止添加不必要的字符串副本的常见错误。 

为了`aace`, 后缀`e`是回文，而较长的后缀则不是。 KMP 发现`k = 1`。 前缀`aac`被反转为`caa`, 给予`aacecaa`。 中心人物`e`自身匹配，而原始前缀镜像在它周围。 

为了`abac`，最长的回文后缀是`c`， 所以`k = 1`。 该算法采用前缀`aba`，将其反转为`aba`，并产生`abacaba`。 这种情况很有用，因为前缀本身恰好是回文，但完整输入不是。 简单地反转整个输入的实现会添加太多字符。 

对于由 4999 个副本组成的最大长度输入`a`其次是`b`，最后的`b`是最长的回文后缀。 KMP 仍然只处理`2n + 1`组合字符串中的字符。 该算法附加了 4999 个副本`a`，生成长度为 9999 的回文。这会执行允许的最大输入，同时还会检查实现是否可以处理非常小的回文后缀，而无需重复扫描候选后缀。
