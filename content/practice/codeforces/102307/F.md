 ## 解决方案
 ## 问题理解

 每个输入行都是由分数、加法、减法和括号构建的算术表达式。 表达式中出现的分数具有从 0 到 100 的分子和从 1 到 20 的正分母。括号可以任意嵌套，因此表达式如`1/2-(3/4-(1/5+1/10))`是有效的。 

对于每个表达式，我们需要其精确的有理值，并且必须将该值打印为分母为正的约分数。 即使输入中出现的每个分数都有一个非负分子，结果本身也可能为负数。 

所有输入行的字符总数最多为`2 * 10^5`。 该界限排除了重复重新扫描表达式的算法，因为二次算法可以粗略地检查`2 * 10^10`最坏情况下的角色。 线性扫描是自然目标。 各个分母最多为 20，这为我们提供了比仅仅具有小输入标记更强的性质：每个分母除以一个固定的小公分母，即最小公分母`1, 2, ..., 20`。 

一些边缘情况可能会破坏粗心的实施。 为了`1/5-2/10`，正确的结果是`0/1`。 保持未约分母会产生诸如`0/10`，它不满足所需的不可约表示。 

为了`1/2-(1/2-2/1)`，正确的结果是`2/1`。 将括号视为普通分组而不记住左括号之前的符号的解析器可能会错误地将表达式计算为`-2/1`或者`-1/1`。 

为了`1/2-3/2`，结果是`-1/1`。 由于所有输入分数都是非负的，假设最终分子必须为非负的实现在这里将会失败。 该限制适用于输入分数，而不适用于表达式的值。 

为了`100/20`，结果是`5/1`。 分母界限是包容性的，因此解析器必须接受 20，而不是意外地将 19 视为最大可能的分母。 

## 方法

 一个简单的暴力解决方案可以重复定位最里面的括号表达式，对其求值，用其结果分数替换整个表达式，然后继续，直到没有括号为止。 每个替换在数学上都是正确的，因为所选括号内的表达式独立于周围的表达式。 

问题是重复扫描。 考虑一个包含一长串嵌套括号的表达式。 第一个搜索几乎扫描整个字符串，下一个搜索几乎扫描整个缩短的字符串，依此类推。 和`n`这需要的字符`Theta(n^2)`性格检查。 在`n = 2 * 10^5`，一条链可以大致导致`n^2 / 2`， 大约`2 * 10^10`，这远远超出了一秒解决方案所能承受的范围。 

递归解析器已经好得多，因为它可以对表达式的每个部分求值一次。 然而，Python 递归在这里是不安全的，因为有效的表达式可能包含接近`2 * 10^5`嵌套括号。 我们可以通过将计算状态明确地保存在堆栈上来完全避免递归。 

还有一个有用的算术简化。 每个输入分母都在 1 到 20 之间，因此每个分母都可以除`L = lcm(1, 2, ..., 20) = 232792560`。 

不要将每个分数存储为单独的分子和分母，而是转换每个输入分数`a/b`化为整数`a * (L / b)`。 

该整数表示原始分数乘以`L`。 由于加法和减法是线性的，因此可以仅使用整数加法和减法来计算整个表达式。 括号仅影响哪个累积整数接收符号，因此它们可以由堆栈处理。 

评估完整表达式后，假设缩放结果为`x`。 实际值为`x/L`。 划分`x`和`L`通过它们的最大公约数给出所需的不可约分数。 

暴力方法重复地重新访问相同的字符，而最优方法处理每个字符一次并将所有分数减少推迟到最后。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了|
 | 最佳 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 设置`L = 232792560`，每个可能的输入分母的最小公倍数。 每个分数`a/b`可以表示为整数`a * (L/b)`，因为它的值恰好是该整数除以`L`。 
2. 从左到右扫描表达式。 维持`value`，当前表达式值，单位为`1/L`， 和`sign`，这是`1`或者`-1`并告诉我们如何添加下一个分数。 
3. 当分数开始时，直接从字符串中读取其分子和分母。 使用以下方法将其转换为公分母`numerator * (L // denominator)`，然后添加`sign * scaled_fraction`到`value`。 我们从不需要浮点运算，因此不存在舍入误差。 
4. 当`+`遇到，设置`sign`到`1`。 当一个`-`遇到，设置`sign`到`-1`。 该符号属于下一项，可以是分数或整个括号表达式。 
5. 什么时候`(`遇到，推当前`value`和`sign`到堆栈上。 然后在括号内开始一个新的表达式`value = 0`和`sign = 1`。 需要保存的符号是因为整个内部表达式之前可能是`+`或者`-`。 
6. 什么时候`)`遇到了，内心的表达就结束了。 弹出保存的外部值和外部符号。 如果内部结果是`inner`，将外部状态替换为`outer_value + outer_sign * inner`。 这将整个带括号的表达式视为一个术语，完全按照语法要求。 
7. 扫描完成后，表达式有值`value / L`。 计算`g = gcd(abs(value), L)`并打印`value // g`超过`L // g`。 在 gcd 中使用绝对值也可以正确处理负结果。 

### 为什么它有效

 不变量是在扫描中的每个点，`value / L`正是当前表达式中已被消耗的部分的值。 这`sign`变量表示等待应用于下一项的运算符。 打开括号可以保存完整的外部状态并启动独立的内部表达式。 关闭它会恢复该状态，并添加计算后的内部表达式，其符号与左括号之前的符号完全相同。 由于每个分数都转换为相同的分母`L`，所有加法和减法都保留由下式表示的精确值`value / L`。 最后，减少`value/L`根据他们的 gcd 只改变表示形式，而不改变数学值，因此打印的分数正是所需的答案。 

## Python 解决方案```python
import sys
from math import gcd

input = sys.stdin.readline

L = 232792560

def evaluate(s):
    n = len(s)
    i = 0

    value = 0
    sign = 1

    # Each stack entry stores:
    # (value before '(', sign that preceded '(')
    stack = []

    while i < n:
        c = s[i]

        if c.isdigit():
            numerator = 0
            while i < n and s[i].isdigit():
                numerator = numerator * 10 + (ord(s[i]) - ord('0'))
                i += 1

            # Skip '/'
            i += 1

            denominator = 0
            while i < n and s[i].isdigit():
                denominator = denominator * 10 + (ord(s[i]) - ord('0'))
                i += 1

            scaled = numerator * (L // denominator)
            value += sign * scaled

        elif c == '+':
            sign = 1
            i += 1

        elif c == '-':
            sign = -1
            i += 1

        elif c == '(':
            stack.append((value, sign))
            value = 0
            sign = 1
            i += 1

        else:  # ')'
            outer_value, outer_sign = stack.pop()
            value = outer_value + outer_sign * value
            i += 1

    g = gcd(abs(value), L)
    return f"{value // g}/{L // g}"

def main():
    out = []

    for line in sys.stdin:
        s = line.strip()
        if s:
            out.append(evaluate(s))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```常数`L`是核心算术优化。 由于每个分母最多为 20，因此它除以最小公倍数`1`通过`20`。 例如，`1/6`变成`L/6`单位，同时`3/10`变成`3L/10`单位。 现在两者都是使用完全相同分母的整数`L`。 

解析器在跳过之前读取完整的分子`/`，然后读取分母。 输入语法中没有一元减号，因此减号始终充当两个有效公式之间的运算符。 

堆栈在每个左括号处存储两个值。 第一个是括号之前计算的所有内容，第二个是等待括号表达式的符号。 重置`value`为零赋予内部表达式自己的累加器。 

当处理右括号时，其中的表达式已经被完全求值。 线路`value = outer_value + outer_sign * value`正是由周围上下文表示的数学运算。 该操作之后，解析器可以正常继续。 

Python整数具有任意精度，因此不存在溢出风险。 更重要的是，公分母是固定的，因此累积的分子仍然不大。 最多有`O(n)`分数，每个分数最多贡献`100L`，给出一个分子，其大小最多为`O(nL)`，而不是所有输入分母的巨大乘积。 

最终的gcd使用`abs(value)`因为`value`可以是负数。 如果`value`为零，`gcd(0, L)`是`L`，所以结果自动变为`0/1`。

 ## 边缘情况

 表达式`1/5-2/10`测试减少到零。 两个分数都变成带分母的整数`L`，并且它们的缩放值相等，因此累加器变为零。 最终的gcd为`gcd(0, L) = L`，生产`0/1`而不是未减少的`0/L`。 

表达式`1/2-(1/2-2/1)`测试附加到整个括号表达式的符号。 在进入括号之前，堆栈存储的是外部值`L/2`并签名`-1`。 内部表达式的计算结果为`L/2 - 2L = -3L/2`。 关闭括号可恢复外部状态并计算`L/2 - (-3L/2) = 2L`，这减少到`2/1`。 相同的机制适用于任何嵌套深度。 

表达式`1/2-3/2`产生`-1/1`。 累加器就变成了`L/2 - 3L/2 = -L`，并且 gcd 约简保留分子中的负号。 否定表达式不需要特殊情况。 

表达式`100/20`直接检查最大允许值。 自从`20`划分`L`，缩放分数是`100 * (L/20) = 5L`，最终的减少给出`5/1`。 转换`L // denominator`是精确的，因为每个允许的分母都是以下的除数`L`。 

深层嵌套的表达式，例如`1/1-(1/1-(1/1-(1/1)))`还演示了为什么显式堆栈优于 Python 中的递归解析。 每个左括号添加一个恒定大小的堆栈条目，每个右括号将其删除。 解析器从不依赖于 Python 调用堆栈，因此即使具有非常深的嵌套的有效表达式仍然是安全的。 

最后，由许多分数组成的非常长的表达式测试实际的输入范围。 解析器不会重复重建或重新扫描表达式，因此其工作量直接随着输入字符的数量而增长。 固定公分母还可以防止分数分母在求值过程中增长，即使在接近分数的情况下也能保持算术效率。`2 * 10^5`字符限制。
