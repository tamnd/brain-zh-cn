 ## 解决方案
 ## 问题理解

 我们有从 1 开始索引的斐波那契序列，其中 (F_1=F_2=1) 和 (F_{k+2}=F_{k+1}+F_k)。 对于给定的 (n)，可用的人员对应于前 (n) 个索引斐波那契值。 我们需要计算那些斐波那契值满足三个有效条件的人类对：他们的 gcd 为 1，他们的和是奇数，他们的和本身就是一个斐波那契数。 

短语“前 (n) 个斐波那契数”意味着指数很重要。 特别是，(F_1) 和 (F_2) 是两个位置，即使两个值都等于 1。这一小重复导致了一对异常的出现，并且很容易被忽视。 官方示例有 6 个查询，输出为 (0,3,5,11,13,17)。 

最大的（n）是（10^5），并且可以有很多测试用例。 二次算法将检查

 [
 \frac{100000\cdot99999}{2}=4,999,950,000
 ]

 最坏情况下成对。 即使有 10 秒的慷慨限制，这也远远超出了竞赛解决方案应尝试的范围。 我们需要利用斐波那契数列的结构，以便可以在恒定时间内处理每个附加位置。 

在一些小情况下，粗心的实施可能会失败。 用于输入`1`，根本没有配对，所以答案是`0`。 用于输入`2`，唯一的一对由 (F_1=1) 和 (F_2=1) 组成，但它们的和是 2，这不是斐波那契，所以答案也是`0`。 简单地计算连续索引的解决方案会意外地接受这一对。 

输入更微妙的情况`3`。 ((F_2,F_3)=(1,2)) 和 ((F_1,F_3)=(1,2)) 都有效，因为它们的总和为 3，gcd 为 1，而 3 是斐波那契数。 因此答案是`2`。 该对 ((F_1,F_2)) 仍然不起作用，因为 (1+1=2)。 假设每个有效对必须具有连续索引的解决方案将只找到一对并产生错误的答案。 

## 方法

 直接的方法是用 (1\leq i,j\leq n) 枚举每对索引 (i<j)。 对于每一对，我们可以测试 gcd 条件，检查 (F_i+F_j) 是否为奇数，并确定该和是否为斐波那契数。 通过预先计算的斐波那契隶属度结构，可以在常数或对数时间内检查每一对。 困难不在于单个检查，而在于配对的数量。 在 (n=100000) 中，有 4,999,950,000 个，因此即使是极其便宜的支票也会太慢。 

关键的观察来自斐波那契递推本身。 假设 (i<j) 和 (j\geq4)。 由于斐波那契数从 (F_2) 开始增加，

 [
 F_j < F_i+F_j < F_j+F_{j-1}=F_{j+1}
 ]

 每当 (i<j-1) 时。 (F_j) 和 (F_{j+1}) 之间不存在严格的斐波那契数，因此其和不可能是斐波那契数。 因此，对于普通索引，有效对必须具有 (i=j-1)。 

有一个异常是由(F_1=F_2)引起的。 该对 ((1,3)) 给出 (1+2=3=F_4)，即使其索引不连续。 这对特殊的配对必须单独计算。 

现在我们剩下 (i\geq2) 的连续对 ((i,i+1))。 它们的 gcd 自动为 1，因为连续的斐波那契数是互质的。 它们的总和恰好是 (F_{i+2})，因此斐波那契和条件也自动满足。 唯一剩下的问题是 (F_{i+2}) 是否为奇数。 

斐波那契奇偶校验重复为

 [
 1,1,0,1,1,0,\l点
 ]

 因此，当 (k) 能被 3 整除时，(F_k) 恰好是偶数。因此，当 (i+2) 不能被 3 整除时，或者等效地当 (i\not\equiv1\pmod3) 时，从 (i) 开始的连续对恰好有效。 

因此整个问题就变成了一个简单的前缀计数问题。 从 (n=3) 开始，我们有例外对 ((1,3))，并且每个新的斐波那契位置都会添加一个新的连续候选值，除非其起始索引与 1 模 3 全等，否则该候选值会被接受。

 | 蛮力 | (O(n^2)) | (O(n)) | (O(n)) | 太慢了|

 ## 算法演练

 1. 读取所有测试用例并找到查询的最大的（n）。 我们只需要不超过该值的答案，因此一个前缀数组足以满足每个查询。 
2. 初始化`ans[1] = 0`和`ans[2] = 0`。 由于位置少于三个，因此不存在完美的配对。 
3. 设置`ans[3] = 2`。 两个有效对是 ((F_1,F_3)) 和 ((F_2,F_3))，均表示值 (1) 和 (2)。 ((F_1,F_2)) 对无效，因为其总和为 2。 
4. 对于每个 (n\geq4)，从`ans[n] = ans[n-1]`。 唯一可能的新对是 ((F_{n-1},F_n))，因为每个旧对都已被计算在内。 
5. 当 ((n-1)\bmod3\neq1) 时接受新对。 它的总和是 (F_{n+1})，并且当 (n+1) 不能被 3 整除时，它是奇数。由于 (n+1\equiv n-2\pmod3)，这相当于 (n-1\not\equiv1\pmod3)。 
6. 只要条件成立就加一。 这会产生一个前缀计数，因此每个查询都可以在 (O(1)) 中得到回答。 

### 为什么它有效

 对于任何具有索引 (i<j) 的对，除了特殊相等 (F_1=F_2) 之外，斐波那契递推将 (F_i+F_j) 严格放置在 (F_j) 和 (F_{j+1}) 之间，除非 (i=j-1)。 因此，每个有效的非例外对都是连续的。 连续的斐波那契数是互质的，它们的和是下一个斐波那契数，因此只剩下奇偶性。 由于斐波那契数的索引甚至可以被 3 整除，因此起始索引不是 (1\bmod3) 的连续对都是有效的。 唯一的附加对是 ((F_1,F_3))，它包含在 (n=3) 处的初始化中。 因此，前缀数组对每个有效对仅计数一次，并且不会对无效对进行计数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    queries = [int(input()) for _ in range(t)]

    mx = max(queries)

    ans = [0] * (mx + 1)

    if mx >= 3:
        ans[3] = 2

    for n in range(4, mx + 1):
        ans[n] = ans[n - 1]

        # The new pair is (F[n-1], F[n]).
        # It is valid iff F[n+1] is odd.
        if (n - 1) % 3 != 1:
            ans[n] += 1

    sys.stdout.write("\n".join(str(ans[n]) for n in queries))

if __name__ == "__main__":
    solve()
```第一部分在预处理之前读取每个查询，因为请求的最大索引决定了前缀数组必须构建多远。 这避免了为多个测试用例单独执行相同的工作。 

初始化于`ans[3] = 2`处理重复值 (F_1=F_2=1) 和涉及 (F_1) 的异常对。 开始于`n=4`保持主循环干净，并防止特殊情况逻辑泄漏到每次迭代中。 

对于每一个新`n`，唯一不存在的对`n-1`是 ((F_{n-1},F_n))。 它的和是(F_{n+1})，因此检查和是否为奇数相当于检查(n+1)是否不能被3整除。代码使用等效条件`(n - 1) % 3 != 1`。 

无需自行构建斐波那契值。 随着 (n) 的增长，它们的大小变得巨大，但证明将问题完全简化为索引算术和斐波那契奇偶校验。 这也避免了 Python 中的任意精度整数工作。 

该数组的长度最多为 100001，因此内存使用量完全在 256 MB 限制之内。 输出是由一个最终生成的`join`，避免重复慢速写入。

 ## 边缘情况

 第一个边缘情况是 (n=1)。 输入```
1
1
```仅包含 (F_1=1)，因此没有两个不同的人可以组成一对。 该算法永远不会进入 (n=3) 的初始化，留下`ans[1]`等于0，这是正确的输出。 

第二个边缘情况是 (n=2)。 唯一可能的对是包含 1 的两个位置。它们的 gcd 为 1，但它们的和为 2，这不是斐波那契数。 该算法离开`ans[2]=0`，因此它不会意外地将重复值视为有效的斐波那契和。 

最重要的索引边缘情况是 (n=3)。 斐波那契值为 (1,1,2)。 由位置2和3形成的对具有和(1+2=3)，并且由位置1和3形成的对具有完全相同的性质。 因此答案是2。初始化`ans[3] = 2`捕获两对。 仅基于连续索引的公式将错过第一个索引。 

对于模 3 边界，请考虑 (n=5)。 新的连续对是 ((F_4,F_5)=(3,5))，其和为 8。由于 8 是偶数，因此该对不满足奇和条件。 这里 (n-1=4\equiv1\pmod3) 正是算法拒绝的残差。 答案仍然是3。 

在 (n=6) 处，新对是 ((F_5,F_6)=(5,8))，其总和为 13，这是一个奇数斐波那契数。 由于 (n-1=5\not\equiv1\pmod3)，算法将答案从 3 增加到 4。这两个连续的情况说明了为什么条件必须基于索引模 3。 

最后，在 (n=100000) 处，从 2 到 99999 有 99998 个可能的普通连续起始索引。其中正好有 33332 个与 1 模 3 全等并且不符合奇偶校验条件，留下 66666 个有效的连续对。 添加例外对 ((F_1,F_3)) 得出`66667`。 该算法仅使用前缀递归即可达到此值，而无需构造巨大的（100000）斐波那契数。
