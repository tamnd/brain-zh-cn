 ## 问题理解

 我们得到一个图，其顶点是豪宅中的房间，其边缘是门。 每扇门都连接两个房间，并标有唯一的钥匙索引。 要穿过门，人当前必须持有钥匙。 穿过后，门会再次关闭，因此钥匙的所有权完全控制了未来的移动。 

两个特工从不同的特殊房间开始：爱丽丝从房间 0 开始，必须到达代表外部的房间 1。 Bob 从房间 1 开始，最终必须到达房间 0。不同的是，钥匙最初是在他们之间分配的，而 Alice 可以将钥匙放在她访问的房间中，但不能放在外面的房间。 鲍勃可以拾取他访问的房间中留下的所有钥匙。 

我们被要求将每个密钥准确地分配给 Alice 或 Bob 之一，然后为两者输出显式移动脚本，以便 Alice 可以从 0 到 1，Bob 可以稍后从 1 到 0，使用可能通过中间房间传输的密钥。 

这些约束允许最多 100,000 个房间和门，因此任何解决方案在边数上都必须基本上是线性的或接近线性的。 任何重复重新计算可达性、模拟多代理状态或尝试搜索分配的策略都将立即超出限制。 4·10^5 的指令预算还意味着任何构建的遍历都必须仔细限制，并且不能不必要地重复遍历大循环。 

一个关键的结构困难是，爱丽丝的路线必须可供鲍勃反向使用，但鲍勃只能在共享访问的房间中获得密钥。 这会在前向遍历和后向遍历之间产生依赖关系，必须通过精心选择的传输点进行对齐。 

当图表的两个方向都需要相同的密钥才能穿过桥边，但爱丽丝不能将其放在外面的房间时，就会出现微妙的失败情况。 例如，如果 0 和 1 之间的唯一连接是一条边，那么 Alice 在穿过它后就无法将其密钥留在任何有用的地方，从而使问题变得不可能。 

另一种故障模式出现在循环图中，其中 Alice 多次重新访问房间。 简单地让 Alice 丢弃“除了最后一个边缘之外的所有密钥”的天真的想法失败了，因为 Bob 可能无法在不重新追踪有效路径的情况下在可达位置收集所需的密钥。 

最后，当密钥被丢弃后需要重新进入区域时，任何假设 Alice 可以独立于遍历结构任意重新排序密钥分配的解决方案都会中断。 

## 方法

 第一个天真的想法是同时模拟 Alice 和 Bob，并尝试针对每条边决定 Alice 或 Bob 是否应该拥有其密钥，以确保两者都能完成其路线。 人们可能会尝试根据来自房间 0 的 DFS 贪婪地分配密钥，并确保 Bob 稍后可以反向到达所有必要的边缘。 这很快就会变得组合复杂，因为 Alice 的路径决定了密钥可以被丢弃的位置，而 Bob 的遍历取决于这些丢弃。 对分配的强力搜索以 m 为指数，甚至对（房间、持有的密钥集）的状态空间搜索以密钥数量呈指数。 

更结构化的观察是，Alice 的移动定义了一个以 0 为根的跨越结构，而 Bob 的反向移动自然对应于从 1 向后遍历该结构。关键思想是分离职责：Alice 用来沿向 1 的定向遍历传输密钥，而 Bob 使用它们返回到 0。密钥传输的唯一方式是在双方访问的共享房间中，这表明该图必须分解为一种结构，其中每条边都在受控方向上使用，并且密钥被传递 仅在精心选择的节点上。

这个问题简化为找到一个遍历结构，保证仅使用 Alice 的密钥存在从 0 到 1 的路径，并且使用可以沿着同一结构传递的密钥存在从 1 到 0 的路径。 实现这一目标的自然对象是一棵以 0 为根的生成树，并通过鲍勃如何从 1 回溯它的定向概念进行了增强。 

核心见解是从节点 0 开始构建 DFS 树，然后定向边缘，以便 Alice 沿着树向下移动并在战略节点的返回边缘上丢弃密钥，从而有效地将密钥暂存在最低共同祖先处。 然后 Bob 从 1 开始执行遍历，反向遍历相同的树结构，在进入子树时收集键。 

这减少了从全局密钥分配到沿着 DFS 树的本地决策的问题，确保每个密钥在受控传输管道中仅使用一次。
