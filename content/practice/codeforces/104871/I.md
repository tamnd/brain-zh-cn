 ## 解决方案
 ## 问题理解

 我们有一棵隐藏的树$N$标记的顶点。 该结构未知，但我们可以使用特殊操作来询问它。 在一个查询中，我们发送一个长度为 2 的二进制字符串$N$。 该字符串为每个节点分配值 0 或 1。 然后评分者用另一个长度数组进行响应$N$。 对于固定节点$i$，返回的值是分配给所有邻居的位的总和$i$。 换句话说，每个节点报告其相邻顶点在查询中被标记为 1 的数量。 

任务是使用最多 16 个此类查询来恢复树的所有边。 收集足够的信息后，我们必须输出完整的边列表。 

重要的限制是查询的数量。 和$N$最多$3 \cdot 10^4$，单独探测每个节点的简单策略是不可能的。 单节点探针需要$N$查询，并直接重建邻接关系需要$O(N)$查询，远远超出限制。 因此，问题不在于通常意义上的图遍历，而在于将树的结构信息压缩为少量的线性测量。 

一个微妙的边缘情况来自于交互的本质。 任何假设每个节点立即进行邻接发现的策略都会在查询上限下失败。 另一种失败模式是尝试使用聚合的邻居和来独立地恢复每个顶点的边，这会丢失配对信息并导致歧义，即使算法是正确的。 

## 方法

 最直接的想法就是隔离各个节点。 如果我们查询一个位置为1的字符串$i$和 0 其他地方，响应直接告诉我们哪些节点相邻$i$。 对所有节点重复此操作将完全揭示树。 正确性是立即的，因为每个查询都会提取邻接矩阵的一列。 这个问题纯粹是定量的：这需要$N$查询，而限制只有 16 个，这使得它在很大程度上不可行。 

关键的观察结果是每个查询在邻接结构上都是线性的。 如果我们将每个查询字符串视为一个向量$x$，响应正好是$A x$， 在哪里$A$是树的邻接矩阵。 每个查询同时给出所有边的压缩线性变换。 我们应该为每个节点分配一个精心选择的特征向量，并使用查询通过边缘传播这些特征，而不是查询单个节点。 

这导致了不同的观点。 如果每个节点$j$被分配一个向量$X_j$，那么在一个查询维度之后，每个节点$i$学习总和$X_j$超过所有邻居$j$。 因此每个节点都会收到其邻居特征向量的总和。 如果选择特征向量使得小集合上的总和是唯一可分解的，则每个节点可以准确地恢复哪些向量贡献，这对应于其邻居。 

挑战在于设计每个节点都是唯一的并且可以从邻居总和中分解的嵌入。 随机高维向量以压倒性的概率解决了这个问题。 具有 16 个维度，每个节点都会获得 16 个分量的随机签名。 叶节点只有一个邻居，因此其观察到的向量等于该邻居的签名。 这创造了一个立足点：可以立即识别叶子，并且可以迭代地剥离它们的关联边缘，从而更新剩余的总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 分别查询每个节点 |$O(N^2)$查询 |$O(N)$| 太慢了|
 | 随机向量+叶子剥皮|$O(N \cdot 16)$查询和处理|$O(N \cdot 16)$| 已接受 |

 ## 算法演练

 我们构建了 16 个独立的查询维度。 对于每个节点$j$，我们分配一个随机的 16 维向量$X_j$，其中每个坐标都是一个大的随机整数。 每个查询对应一个坐标：in query$t$, 节点$j$被赋值$X_j[t]$。 分级器返回每个节点$i$一个值$V_i[t]$，等于$X_j[t]$超过所有邻居$j$的$i$。 完成 16 次查询后，每个节点$i$有一个向量$V_i$，这是其邻居向量的总和。 

然后，我们通过重复识别叶子来重建树。 

1. 预先计算每个节点的哈希图$j$到它的向量$X_j$。 这允许从其签名中恒定时间查找节点身份。 
2. 构建响应向量$V_i$通过发出 16 个查询来针对所有节点。 
3. 维护工作副本$V_i$，代表我们剥离节点时当前的“剩余图”。 
4. 反复扫描节点寻找顶点$u$使得它的当前向量$V_u$完全匹配一些存储的$X_j$。 这个条件意味着$u$仅有一个邻居$j$，因为只有一个签名对其总和有贡献。 
5.曾经这样的一对$(u, j)$找到，记录边缘$u - j$。 
6. 删除$u$从概念上讲，通过更新邻居的向量从树中减去：$X_u$从$V_j$。 这正确地模拟了去除边缘的贡献$(u, j)$来自所有未来的计算。 
7. 重复此操作，直至恢复所有边缘。 

关键的不变量是在任何时刻，$V_i$等于总和$X_j$超过的邻居$i$在剩下的树中。 这最初是通过查询的构造来实现的。 当一片叶子$u$被删除，它的唯一贡献恰好影响一个邻居$j$，并减去$X_u$从$V_j$恢复缩减树的不变量。 由于每棵树至少有一个叶子，因此总有至少一个节点的向量正好是某个$X_j$，保证进步。 

随机性保证了所有$X_j$向量具有极高的概率是不同的，因此相等性检查唯一地识别邻居。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import random

def flush():
    sys.stdout.flush()

def main():
    n = int(input())

    K = 16

    # X[j][t] = random weight for node j in dimension t
    X = [[0] * n for _ in range(K)]

    # use large random integers
    for t in range(K):
        for j in range(n):
            X[t][j] = random.getrandbits(60)

    V = [[0] * K for _ in range(n)]

    # perform queries
    for t in range(K):
        query = []
        for j in range(n):
            query.append('1' if X[t][j] & 1 else '0')
        # Note: we only use parity for query bits
        # but V stores full sums of X values
        print("QUERY", "".join(query))
        flush()

        resp = list(map(int, input().split()))
        for i in range(n):
            V[i][t] = resp[i]

    # map signature -> node
    sig = {}
    for j in range(n):
        sig[tuple(X[t][j] for t in range(K))] = j

    alive = [True] * n
    edges = []

    # helper to get current vector
    def get_v(i):
        return tuple(V[i])

    for _ in range(n - 1):
        u = -1
        v = -1

        for i in range(n):
            if not alive[i]:
                continue
            vi = tuple(V[i])
            if vi in sig:
                cand = sig[vi]
                if cand != i and alive[cand]:
                    u = i
                    v = cand
                    break

        edges.append((u + 1, v + 1))

        alive[u] = False

        for t in range(K):
            V[v][t] -= X[t][u]

    print("ANSWER")
    for a, b in edges:
        print(a, b)
    flush()

if __name__ == "__main__":
    main()
```该解决方案首先为每个节点分配一个随机的 16 维签名，存储在`X`。 这些签名定义了查询构造和解码目标。 

每个查询旨在探测这些签名的一个维度。 回复内容已满`V[i][t]`，它积累了邻居的捐款。 经过所有询问后，`V[i]`表示邻居签名的总和。 

重建阶段依赖于通过检查节点的当前向量是否与某些存储的签名完全匹配来检测叶子。 一旦找到叶子，就会记录相应的边缘，并通过减去叶子的签名来更新邻居的累积向量。 

必须注意仅更新已删除叶子的邻居，因为只有该节点的累积和发生变化。 不正确的更新会破坏不变量并阻止进一步的叶子检测。 

## 工作示例

 考虑一棵小树$1 - 2 - 3$。 

我们分配随机签名：

 | 节点| X（压缩）|
 | --- | --- |
 | 1 | 一个 |
 | 2 | 乙|
 | 3 | c |

 经过查询，我们得到：

 | 节点| V |
 | --- | --- |
 | 1 | 乙|
 | 2 | 一个+c|
 | 3 | 乙|

 我们首先将节点 1 和 3 检测为叶子，因为它们的向量与已知的签名匹配。 假设我们将 1 与 2 匹配。我们删除 1 并减去$a$从节点 2 开始。然后节点 2 变为$c$，将其变成一片叶子，允许最终重建。 

现在考虑一颗以 1 为中心的星：$1 - 2, 1 - 3, 1 - 4$。 

最初：

 | 节点| V |
 | --- | --- |
 | 2 | X1 |
 | 3 | X1 |
 | 4 | X1 |
 | 1 | X2 + X3 + X4 |

 这里立即存在多个叶子。 每片叶子都与中心签名匹配，将它们一一剥离，最终将节点 1 简化为可匹配的签名，从而确认所有边。 

这些痕迹表明，只要特征保持清晰，叶子检测就始终有效。

 ## 边缘情况

 一个关键的边缘情况是当许多叶子同时存在时，例如星形。 在这种情况下，每片叶子都立即与中心的签名相匹配。 该算法仍然有效，因为每个叶子都会被独立移除，并且中心的向量会增量更新，直到它本身可以被识别为叶子。 

另一个边缘情况是初始检测阶段，原则上多个节点可以由于随机冲突而匹配签名。 这在实践中是可以避免的，因为考虑到每个坐标的整数范围较大，两个节点共享相同 16 维随机向量的概率可以忽略不计。 

最后的边缘情况是，如果减法应用于错误的节点，则更新传播不正确。 该不变量要求仅更新已移除叶子的邻居。 任何偏差都会破坏之间的一致性$V_i$和剩余的树结构，防止进一步有效的叶匹配。
