 ## 解决方案
 ## 问题理解

 我们有一家面包店，可以生产多种类型的蛋糕。 每个蛋糕配方都会消耗一定量的原料，并且需要一套可重复使用的工具。 每一种原料、每一种工具都有成本，每块蛋糕也有售价。 

关键的决定是在每个食谱最多只能使用一次的限制下烘烤哪个子集的蛋糕。 如果我们选择一个蛋糕，我们必须支付它所需的所有原料和所有所需的工具，然后我们才能赚取它的售价。 工具不会被消耗，但如果任何选定的蛋糕需要它们，仍然必须购买它们，因此它们的成本在全球范围内最多支付一次，而原料则按每个蛋糕支付。 

目标是最大化总利润，定义为所选蛋糕的总收入减去所有使用的原料和所有购买的工具的成本。 

输入描述了原料成本、工具成本，以及每个蛋糕需要的每种原料的数量以及所需的工具。 输出是一个数字：可实现的最佳利润。 

这些限制表明最多有几百个蛋糕、配料和工具。 对蛋糕所有子集的简单枚举已经意味着多达 2^200 种可能性，这是完全不可行的。 任何解决方案都必须避免对蛋糕数量的指数依赖。 

一个微妙的建模点是工具成本在蛋糕之间共享，这会在决策之间产生耦合。 如果一个工具被至少一个选定的蛋糕使用，则其成本仅支付一次。 这打破了蛋糕之间的独立性，并使问题变得不那么简单。 

当一个蛋糕单独盈利但由于共享工具成本而变得无利可图时，或者当一个工具很昂贵但只需要一次时，就会出现边缘情况，使其摊余成本变得至关重要。 例如，两个蛋糕可能每个都需要非常昂贵的工具； 仅使用一个蛋糕就需要支付全部工具成本，而同时使用两个蛋糕不会进一步增加工具成本，与每个蛋糕评估相比，这可以翻转最佳选择。 

## 方法

 直接的暴力方法会考虑蛋糕的每个子集。 对于每个子集，我们通过对每个蛋糕的贡献求和来计算总成分成本，并通过采用所需工具的并集来计算工具成本。 这是正确的，因为它直接评估利润的定义。 

然而，这需要迭代 2^C 个子集。 即使计算每个子集成本优化为 O(G + T)，总复杂度也变为 O(2^C (G + T))，这远远超出了 C 在 200 左右时的可行极限。 

实现更快解决方案的结构来自于将成分与工具分开。 每个蛋糕的原料成本是累加的，因此它们呈线性且独立的贡献。 工具成本仅取决于是否至少有一个选定的蛋糕使用它们，这意味着工具的行为类似于设定覆盖范围：如果至少选择一次，每个工具都会产生固定的惩罚。 

这将问题转化为选择蛋糕，其中每个蛋糕贡献线性利润，但会因激活工具而受到额外惩罚。 关键思想是转变视角：不要考虑每个蛋糕，而是考虑每个工具子集。 由于 T 也最多为 200，因此我们可以将工具使用视为一种状态，并使用工具掩码上的 DP 或工具子集上的类似背包的聚合来组合蛋糕贡献。 可以预先计算每个蛋糕的成分，只留下工具交互作为困难部分。 

我们计算每个蛋糕的内在价值，忽略工具，然后通过工具的子集 DP 处理工具成本：对于每个工具子集，我们汇总工具需求包含在该子集中的蛋糕可实现的最佳利润。 这减少了耦合并允许在 2^T 状态而不是 2^C 上进行动态编程。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对蛋糕子集的暴力破解 | O(2^C (G + T)) | O(2^C (G + T)) | O(1) 或 O(C) | 太慢了 |
 | 工具子集上的 DP | O(2^T * C) | O(2^T * C) | O(2^T) | O(2^T) | 已接受 |

 ## 算法演练

 ## 最优算法

 1. 对于每个蛋糕，通过将所需数量乘以原料价格求和来计算其原料成本。 从其销售价格中减去此值即可获得忽略工具的基本利润。 这隔离了附加贡献，因此工具成为唯一的耦合因素。 
2. 对于每个蛋糕，将其工具要求表示为 T 工具上的位掩码。 这会将工具集转换为紧凑整数，因此可以使用按位逻辑完成子集运算。 
3. 在所有工具掩码上构建一个数组 dp，初始化为负无穷大，除了 dp[0] = 0。每个状态代表使用选定的蛋糕集合可实现的最佳利润，这些蛋糕的所需工具完全被该掩码覆盖。 
4. 对于每个蛋糕，按降序对所有蒙版执行背包式更新。 如果我们拿下这个蛋糕，我们就会从当前掩码 m 过渡到 m OR mask[cake]，并添加其基本利润。 该模型激活了迄今为止所需的所有工具以及该蛋糕的工具。 
5. 加工完所有蛋糕后，应用工具成本。 对于每个掩模，减去掩模中包含的工具的总成本。 这是通过使用标准子集 DP 预先计算子集上的工具成本总和来完成的。 
6. 答案是应用工具成本后所有掩模的最大值。 

降序更新是必要的，因此每个蛋糕最多使用一次。 如果我们按递增顺序更新，则可以通过中间状态对同一个蛋糕进行多次计数。 

### 为什么它有效

 DP 不变量是在处理前 k 个蛋糕后，dp[m] 使用这些 k 个蛋糕的工具并集恰好为 m 的任何子集存储可实现的最大基本利润。 每个转换要么排除要么包含当前的蛋糕，并且包含它会通过按位或正确合并工具要求。 由于每个蛋糕都被考虑一次，因此任何州都不能多次包含它。 最终扣除的工具成本正确地对每个掩模每个工具收取一次费用，与原始成本定义相匹配。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    G, C, T = map(int, input().split())
    c = list(map(int, input().split()))
    g = list(map(int, input().split()))
    t = list(map(int, input().split()))

    # ingredient matrix
    A = [list(map(int, input().split())) for _ in range(C)]

    tool_mask = [0] * C
    tool_list = []
    for i in range(C):
        parts = list(map(int, input().split()))
        k = parts[0]
        mask = 0
        for x in parts[1:]:
            mask |= 1 << (x - 1)
        tool_mask[i] = mask

    # base profit per cake (ignore tools for now)
    base = [0] * C
    for i in range(C):
        cost = 0
        for j in range(G):
            cost += A[i][j] * g[j]
        base[i] = c[i] - cost

    # dp over tool masks
    N = 1 << T
    dp = [-10**30] * N
    dp[0] = 0

    for i in range(C):
        m = tool_mask[i]
        val = base[i]
        if val <= 0 and m == 0:
            continue
        for mask in range(N - 1, -1, -1):
            if dp[mask] < -10**20:
                continue
            nm = mask | m
            dp[nm] = max(dp[nm], dp[mask] + val)

    # compute tool cost per mask
    cost_mask = [0] * N
    for i in range(T):
        bit = 1 << i
        for mask in range(N):
            if mask & bit:
                cost_mask[mask] += t[i]

    ans = 0
    for mask in range(N):
        ans = max(ans, dp[mask] - cost_mask[mask])

    print(ans)

if __name__ == "__main__":
    main()
```每个蛋糕的配料成本计算一次，确保线性预处理。 DP 循环在掩模上小心地向后迭代，因此每个蛋糕最多贡献一次。 位掩码构造对工具集进行编码，因此联合运算变成或运算。 

一个微妙的点是，除了 dp[0] 之外，用一个大的负值而不是零来初始化 dp，因为无法到达的状态一定不会对转换产生影响。 另一个重要的细节是正确处理负基本利润：如果具有负贡献的蛋糕能够在多个盈利蛋糕之间共享昂贵的工具，那么它们仍然有用。 

## 工作示例

 ### 示例 1

 考虑一个带有两个蛋糕和两个工具的简化案例。 

蛋糕 1 的基本利润为 10，并使用工具 A。 

蛋糕 2 的基本利润为 8，并使用工具 A 和 B。 

工具成本各5。 

我们跟踪 dp 状态：

 | 步骤| 蛋糕| 面膜前 | 过渡| 面膜后 | dp值|
 | ---| ---| ---| ---| ---| ---|
 | 初始化| - | 00 | 00 - | 00 | 00 0 |
 | 1 | 蛋糕1 | 00 | 00 00 → 01 (+10) | 01 | 10 | 10
 | 1 | 蛋糕1 | 01 | 01 → 01 (+10) 跳过 | 01 | 10 | 10
 | 2 | 蛋糕2 | 00 | 00 00 → 11 (+8) | 11 | 11 8 |
 | 2 | 蛋糕2 | 01 | 01 → 11 (+18) | 11 | 11 18 | 18

 DP 之后，减去每个掩模的工具成本：

 掩码 01 成本 = 5，价值 = 10 − 5 = 5

 掩码 11 成本 = 10，价值 = 18 − 10 = 8

 最好是8。 

该轨迹显示了共享工具 A 如何改变最优选择：合并蛋糕可以提高工具成本汇总后的利润。 

### 示例 2

 两个蛋糕，没有工具。 

蛋糕1利润3，蛋糕2利润4。 

| 步骤| 蛋糕| 面膜| DP |

 ## 边缘情况

 一个关键的边缘情况是当蛋糕有正收入但工具极其昂贵时。 DP 正确地避免选择它，除非它的包含有助于在同一工具集下组合多个蛋糕。 例如，如果蛋糕 A 单独需要成本为 100 的工具并产生利润 10，则 dp[mask] 在减去之前将为正，但在减去工具成本后变为负，确保不选择它。 

另一个边缘情况是多个蛋糕共享相同的工具集。 DP将他们的基本利润汇总到同一个面具中，在减去一次工具成本后，它正确地反映了无论有多少蛋糕使用工具，工具只支付一次。 

第三种情况是蛋糕没有工具。 它的掩码为零，因此它始终直接贡献于 dp[0]，并且不影响工具成本，与问题定义完全匹配。
