 ## 解决方案
 ## 问题理解

 我们会得到几天内每次提交更改的行数。 我们可以从任何单个提交中重复添加或删除一行，目标是使提交大小分散，以便每对最终值至少相差`d`。 任务是找到所需的最少单行编辑次数。 

对于一个测试用例，输入包含提交数量、任意两个最终提交大小之间所需的最小距离以及原始大小。 输出是达到一组有效的提交大小所需的最小移动总量。 在此过程中提交大小绝不能变为负数，但由于我们构造的最终值是非负数，因此直接移动到它们永远不需要低于零。 

所有测试用例的提交总数可以达到一百万。 这排除了比较多对提交或尝试许多可能的最终配置的解决方案。 解决方案围绕`O(n log n)`或者`O(n)`需要每个测试用例。 提交大小的值很大，因此实现还必须避免基于小坐标的假设。 

一些边缘情况很容易被错误处理。 如果每个值都相同，那么简单地将它们分布在原始值周围可能不是最佳的，因为最便宜的安排可能会导致某些值向下移动，有些值向上移动。 例如：```
1
4 1
0 0 0 0
```答案是`4`。 只增加后面元素的粗心方法会产生`0,1,2,3`和成本`6`，而最佳最终值为`-1,0,1,2`但值不能变为负数。 非负限制将第一个值更改为`0`，给出最终值`0,1,2,3`和成本`6`。 这个例子揭示了一个重要的细节：原始语句的约束意味着我们不能自由地将整个解决方案转移到零以下。 

另一个棘手的情况是原始订单未排序。 编辑后日期本身没有任何关系，因此保留输入顺序可能会给出错误的答案。 例如：```
1
3 10
100 0 50
```这些值首先应排序为`0,50,100`。 根据输入顺序分配最终位置会浪费编辑，因为最小的原始值应该接收最小的最终值。 

第三种情况是变换后的值恰好位于边界上。 例如：```
1
3 5
0 5 10
```答案是`0`，因为这些值已经至少相差`5`。 使用严格的算法`>`比较而不是`>=`会错误地添加更改。 

## 方法

 一种直接的暴力想法是对值进行排序并尝试逐一选择最终值。 一旦第一个最终值固定，接下来的每个值都有一个下限，因为它必须至少`d`比前一个大。 尝试许多可能的起点或许多可能的最终位置很快就变得不可能。 即使检查每个值的所有可能的位置，也需要远远超过可用的操作`n`达到数十万。 

排序后结构变得更简单。 在最优解中，最小的原始值分配给最小的最终值，第二小的分配给第二小的值，依此类推。 这遵循绝对差异的通常交换论点：如果两个分配交叉，交换它们不能增加总距离。 

令排序后的值是`a`。 最终值必须满足：```
y[0] <= y[1] - d <= y[2] - 2d <= ...
```有用的转变消除了强制性的差距。 定义：```
b[i] = a[i] - i*d
```并让：```
x[i] = y[i] - i*d
```现在条件就变得简单了：```
x[0] <= x[1] <= ... <= x[n-1]
```问题变成了寻找最接近的非递减序列`b`绝对距离下。 这是经典的一维 L1 等渗回归问题。 

对于 L1 等渗回归，违反递增顺序的连续组将被合并。 每个合并的组都会收到一个等于该组元素中值的公共值。 中位数是最佳的，因为到所选值的绝对距离之和在任何中位数处都最小。 

我们可以使用池相邻违规者算法来维护这些组。 当新值使最后两组无效时，它们将被合并。 所有合并后，每个组的贡献是其元素到组中位数的距离之和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) 或更糟 | O(n) | 太慢了|
 | 最佳| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对提交大小进行递增排序。 这让我们假设最终值也是按递增顺序排列的，因为交叉分配不能提高绝对差异成本。 
2. 从每个位置减去所需的间距。 对于索引处的值`i`， 创造：```
b[i] = sorted[i] - i*d
```现在的问题是要使`b`非递减，同时最小化总绝对变化。 

1. 使用组从左到右处理值。 每个组存储必须共享相同最终等渗值的所有转换值。 最初，每个值都形成自己的组。 
2. 每当前一组的中位数大于当前组的中位数时，合并两组。 违反了递增条件，因此两组不能保持分离。 
3. 所有合并完成后，计算每个组的成本。 选择组值的中位数，然后添加与该中位数的绝对差值之和。 
4. 将转换问题的结果添加为所需的编辑次数。 

为什么它有效：转换仅删除固定间距要求，因此每个有效的最终排列完全对应于非递减转换排列。 池相邻违规者算法不断精确地合并单调约束被打破的地方。 合并的块必须有一个公共值，而中位数是使该块内的 L1 误差最小化的值。 由于解决了所有可能的违规，并且每个块都是单独最优的，因此最终序列是全局最优的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Block:
    __slots__ = ("vals", "left", "right")
    def __init__(self, vals):
        self.vals = vals
        self.left = 0
        self.right = len(vals) - 1

    def size(self):
        return self.right - self.left + 1

    def median(self):
        return self.vals[(self.left + self.right) // 2]

def solve():
    z = int(input())
    ans = []

    for _ in range(z):
        n, d = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        blocks = []
        for i, x in enumerate(a):
            blocks.append(Block([x - i * d]))
            while len(blocks) >= 2:
                x = blocks[-2]
                y = blocks[-1]
                if x.median() <= y.median():
                    break
                merged = sorted(x.vals[x.left:x.right + 1] + y.vals[y.left:y.right + 1])
                blocks.pop()
                blocks.pop()
                blocks.append(Block(merged))

        res = 0
        for block in blocks:
            m = block.median()
            for x in block.vals:
                res += abs(x - m)

        ans.append(str(res))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```排序步骤将值按照最佳分配必须遵循的顺序排列。 减法为`i*d`消除连续提交之间的强制距离，将原始条件变成普通的单调性。 

这`blocks`stack 表示转换后的数组的当前分区。 每个块都已在内部排序，并具有代表其最佳可能常数值的中值。 当两个相邻中位数乱序时，唯一有效的修复是将它们组合成一个更大的块。 

该实现将实际值存储在每个块内，因为在所有合并之后我们需要计算最终的 L1 成本。 所有块中存储值的总数保持线性。 Python 整数可以安全地处理大的中间和，这很重要，因为答案可能超过 32 位范围。 

## 工作示例

 对于第一个样本：```
1
4 1
0 0 0 0
```转换后的值为：

 | 索引 | 排序值 | 转化后的价值| 行动|
 | ---| ---| ---| ---|
 | 0 | 0 | 0 | 创建块|
 | 1 | 0 | -1 | 与前一个块合并 |
 | 2 | 0 | -2 | 与前一个块合并 |
 | 3 | 0 | -3 | 与前一个块合并 |

 变换后的序列成为一个块，其中包含`[-3,-2,-1,0]`。 其中位数可以是`-2`或者`-1`，给出变换成本`4`。 然而，如果我们直接向后移动，第一个最终值将为负，因此非负要求强制最小最终值为零。 结果值为`0,1,2,3`，给出答案`6`。 

对于第二个样本：```
1
4 10
1 100 5 10
```排序后：```
[1, 5, 10, 100]
```转换后的值为：

 | 索引 | 排序值 | 转化后的价值| 当前区块 |
 | ---| ---| ---| ---|
 | 0 | 1 | 1 | [1] |
 | 1 | 5 | -5 | [1,-5] 合并 |
 | 2 | 10 | 10 -10 | 前一个块合并 |
 | 3 | 100 | 100 70 | 70 最后一个单独的块|

 前三个值形成一个块。 中位数为`[-10,-5,1]`是`-5`，有成本`11`。 最后一个区块的成本`0`。 总计为`11`。 

此跟踪显示了如何将太接近的值分组在一起，而不是独立固定。

import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline
    z = int(data())
    out = []
    for _ in range(z):
        n, d = map(int, data().split())
        a = list(map(int, data().split()))
        a.sort()
        blocks = []

        class B:
            def __init__(self, v):
                self.v = v
            def med(self):
                return self.v[(len(self.v) - 1) // 2]

        for i, x in enumerate(a):
            blocks.append(B([x - i * d]))
            while len(blocks) > 1 and blocks[-2].med() > blocks[-1].med():
                merged = sorted(blocks[-2].v + blocks[-1].v)
                blocks.pop()
                blocks.pop()
                blocks.append(B(merged))

        ans = 0
        for b in blocks:
            m = b.med()
            ans += sum(abs(x - m) for x in b.v)
        out.append(str(ans))

    sys.stdin = old
    return "\n".join(out)

 ## 边缘情况

 对于全平等的情况：```
1
4 1
0 0 0 0
```变换后的值为`0,-1,-2,-3`。 每个新值都会违反之前的中值，因此所有元素都会合并到一个块中。 中位数最小化了变换后的运动，并且在尊重非负最终值之后，提交变为`0,1,2,3`。 该算法通过合并来处理重复值，而不是独立处理每个提交。 

对于未排序的情况：```
1
3 10
100 0 50
```排序给出`0,50,100`。 变换后的值为`0,40,80`，已经是非减的，因此该算法保留三个单独的块。 添加回偏移后，最终值已经正确间隔，从而产生最小成本。 这避免了保留输入顺序的错误。 

对于精确边界情况：```
1
3 5
0 5 10
```变换后的值为`0,0,0`。 这些块合并是因为允许相等的转换值。 最终顺序可以保留`0,5,10`，总运动为零。 这证实了该条件是基于`>= d`，不是严格的不等式。
