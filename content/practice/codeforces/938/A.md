 ## 解决方案
 ## 问题理解

 该任务描述了对字符串的转换，其中根据涉及元音的本地规则删除某些字符。 我们得到一个单词并反复修改它，直到没有两个相邻的元音剩余。 修改规则是特定的：每当我们看到一个元音前面有另一个元音时，我们就删除这两个元音中较早的一个。 

解释这一点的一个有用方法是简化字符串，以便元音永远不会连续出现。 然而，这个过程并不是简单的全局清理。 它是顺序的：删除取决于先前形成的邻接，并且删除字符可以创建也必须处理的新的相邻元音对。 

输入由单个小写拉丁字母字符串组成。 输出是应用所有此类删除后的最终稳定形式。 

由于字符串长度最多为 100，因此任何线性或二次模拟都是可接受的。 重复扫描字符串并删除字符的简单方法仍然可以轻松通过。 更重要的是处理删除后邻接的动态性质。 

一些边缘情况很重要：

 一种边缘情况是完全由元音组成的字符串，例如“aeiou”。 每次删除后，都会形成新的邻接关系，并且该过程将继续下去，直到只剩下一个元音。 如果粗心的实现仅删除单次中第一次出现的一对，那么就会过早停止。 

另一个边缘情况是交替模式，如“abaeio”。 这里只有元音-元音相邻很重要，辅音充当分隔符。 全局处理任何重复元音而不是仅处理连续位置的错误方法会错误地删除有效字符。 

最后，长度为 1 或 2 的字符串通常会终止或只需要一次检查，但它们经常会在扫描逻辑中暴露出差一错误。 

## 方法

 直接的强力模拟完全按照所描述的方式反映了该过程。 我们从左到右重复扫描字符串，每当找到两个连续的元音时，我们就删除较早的一个并重新开始扫描。 这是正确的，因为它从字面上遵循了问题陈述。 

然而，这种方法可能会退化为二次或更糟糕的行为。 在像“aaaaaa”这样的字符串中，每次删除都会移动字符串并强制重新扫描，从而导致大约 O(n²) 操作。 虽然这里 n 很小，但这种方法在概念上变得低效并且更难以推理。 

关键的观察是我们永远不需要从头开始扫描。 相反，我们可以一次性处理字符串，同时维护表示当前有效前缀的结构。 每个新角色仅与最后保留的角色交互。 如果两者都是元音，我们丢弃前一个； 否则我们会正常附加。 

这将问题转化为经典的流式缩减，其中我们维护一个类似堆栈的输出缓冲区。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n²) | O(n) | 已被接受但效率低下 |
 | 基于堆栈的单通道| O(n) | O(n) | 已接受 |

 ## 算法演练

 我们从左到右处理字符，同时维护不断增长的结果列表。

1. 初始化一个空列表，用于存储当前有效字符。 这充当代表校正后的前缀的堆栈。 
2. 定义辅助条件来检查字符是否为元音，其中元音为 a、e、i、o、u、y。 这种分类在整个算法中都是固定的。 
3. 按顺序迭代输入字符串中的每个字符。 
4. 对于每个字符，检查结果列表是否非空以及结果中的当前字符和最后一个字符是否都是元音。 如果这个条件成立，则意味着我们有一个禁止的连续元音对。 
5. 如果条件为真，则从结果列表中删除最后一个字符。 我们还没有附加当前字符，因为规则指定删除较早的元音。 
6. 处理可能的删除后，将当前字符追加到结果列表中。 
7. 继续，直到处理完所有字符。 
8. 将结果列表连接成字符串并输出。 

我们只检查最后一个字符的原因是所有早期的结构都已经保证有效。 任何违规行为都必须涉及新添加的角色和最近幸存的角色。 

### 为什么它有效

 不变量是，在处理字符串的每个前缀之后，结果列表包含该前缀的没有连续元音的版本。 每个步骤都会保留此属性。 添加新字符时，唯一可能的新违规发生在该字符与最后保留的字符之间。 如果两者都是元音，则删除前一个字符会恢复有效性，而不会影响较早的结构，因为较早的字符已被验证并且无法与当前字符形成新的邻接关系。 

这确保了在扫描结束时，输出中的任何位置都不会保留连续的元音。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

VOWELS = set("aeiouy")

def solve():
    n = int(input())
    s = input().strip()
    
    res = []
    
    for ch in s:
        if res and ch in VOWELS and res[-1] in VOWELS:
            res.pop()
        res.append(ch)
    
    print("".join(res))

if __name__ == "__main__":
    solve()
```实现完全遵循进程的堆栈解释。 关键的微妙之处在于，弹出元音后，我们仍然附加当前字符，因为该规则仅删除该对中较早的元音，而不是当前的元音。 

使用列表作为堆栈可以避免重复的字符串重建，否则会带来二次开销。

 ## 边缘情况

 对于像“aeiouy”这样完全元音重的字符串，每当有新元音到达时，算法都会重复删除前一个元音。 从“a”开始，添加“e”删除“a”并保留“e”，然后“i”删除“e”，依此类推。 最终结果只是“y”，这证实了只有一个元音可以在完全连续的链中生存的不变量。 

对于单字符输入，例如“a”，循环运行一次，堆栈开始为空，然后直接追加字符。 不发生比较，并且输出保持不变，这表明边界条件不会触发无效移除。
