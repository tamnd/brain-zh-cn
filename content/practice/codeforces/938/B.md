[CF 938B - 争夺奖品](https://codeforces.com/problemset/problem/938/B)

 **评分：** 1100
 **标签：** 暴力、贪婪
 **求解时间：** 1m 10s
 **已验证：** 是的

 ## 解决方案
 ## 问题理解

 我们在数轴上得到一组代表奖品的不同点。 两个人从固定位置开始，一个从左边的位置 1 开始，另一个从最右边的位置 106 开始。每一秒，任何一个人都可以向左或向右移动一步，当有人恰好落在奖品位置上时，就会立即领取该奖品。 所有奖品必须收集完毕，每个奖品可以分配给任何人。 两人同时移动，因此总时间由最后一次领取奖品的时间决定。 

任务是决定如何在两个人之间分配奖品以及他们应该如何移动，以便最大限度地减少收集所有奖品的时间。 

关键限制是奖金最多可达 100,000 个，头寸最多可达 10^6。 这排除了尝试两个人之间所有奖励分配的任何解决方案，因为这将是 n 的指数并且远远超出可行的限制。 即使对数组分区进行二次动态规划也会太慢。 

当所有奖品都非常接近起始位置之一时，就会出现微妙的边缘情况。 例如，如果所有奖项都接近 1，则最佳解决方案会完全忽略最右边的人，即使他们从位置 106 开始。相反，如果所有奖项都接近 106，则左边的人几乎不相关。 仅根据每个奖品最近的起始位置进行分配的天真贪婪会失败，因为它忽略了全局排序效应。 

另一个棘手的情况是奖品分布在中间。 例如，对于 2、50、51、100 等位置，每个奖项的本地决策可能会导致不必要的回溯，从而显着增加总时间。 

## 方法

 暴力方法会尝试将每个奖品分配给左边的人或右边的人。 对于每个任务，我们将所需的时间计算为两个行程时间的最大值，其中每个人按排序顺序访问其分配的点。 即使我们固定一个分配，计算旅行成本也是线性的，但是有 2^n 个分配，所以这变成了 2^n 乘以 n，这对于 n 高达 10^5 来说是完全不可行的。 

关键的观察结果是，奖品已经按位置排序，并且两个人都沿着同一条线独立移动。 这意味着最佳解决方案的结构不取决于任意交错，而是取决于我们如何将排序列表拆分为主要由一侧处理的前缀和由另一侧处理的后缀。 

我们不考虑任意分配，而是考虑一个分割点 k，使得 k 左边的所有奖品以协调的方式处理，而右边的所有奖品由其他玩家处理。 由于运动是一维的，并且两个智能体都连续运动，因此最优策略有效地简化为选择“左主导”和“右主导”之间的边界。 

对于任何分组，我们都会计算每个人需要多长时间才能覆盖自己的一侧，并考虑到他们在获得最后一个奖品后不需要返回到起始位置。 答案是所有分割点的最小可能的最大时间。 

这将问题从指数分配减少到检查 n 个可能的分割。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n·n) | O(2^n·n) | O(n) | 太慢了|
 | 最佳 | O(n) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们假设奖品按给定的顺序排序。

1. 考虑从 0 到 n 的分割索引 k，其中奖品 [0..k-1] 由左边的人处理，[k..n-1] 由右边的人处理。 这模拟了沿线划分责任的所有可能方式。 
2. 对于左边的人，如果他们拿到奖品[0..k-1]，他们所需的时间就是从1到该段中最远分配的奖品的距离，因为他们只需要到达他们必须收集的最远点。 这是 max(|1 - a[0]|, |1 - a[k-1]|)，但由于该段按排序顺序是连续的，因此主要成本是到达端点。 
3. 对于从 106 开始处理奖品 [k..n-1] 的合适人选，他们的时间取决于到达其分段中最近和最远的点。 由于运动是线性的，因此它们最多只能走到较近的一端并扫过。 这变为 max(|106 - a[k]|, |106 - a[n-1]|)。 
4. 对于每个分割 k，计算两次的最大值。 这代表两个人完成该任务所需的时间。 
5. 取所有 k 中的最小值。 

更仔细的简化消除了多余的情况：左段成本主要取决于到达左侧的最后一个元素，而右段成本取决于到达右侧的第一个元素。 这允许每个分割进行 O(1) 计算。 

### 为什么它有效

 核心不变量是，在一个维度上，一旦一个人致力于收集连续的点段，最佳路径是单调的：他们从起点向该段移动，然后扫过而不会不必要地回头。 任何跨线交替分配任务的解决方案都可以转变为将责任分组到单个边界划分中而不增加总时间的解决方案，因为额外的交叉只会增加距离而不会增加收集的收益。 这将搜索空间减少到 n+1 个单调分区。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # prefix and suffix boundaries
    INF = 10**18
    
    ans = INF
    
    for k in range(n + 1):
        # left person takes [0..k-1]
        if k == 0:
            left_time = 0
        else:
            left_time = abs(1 - a[k-1])
        
        # right person takes [k..n-1]
        if k == n:
            right_time = 0
        else:
            right_time = abs(106 - a[k])
        
        ans = min(ans, max(left_time, right_time))
    
    print(ans)

if __name__ == "__main__":
    solve()
```该实现直接评估所有分割点。 左边的人的成本仅由其分配的前缀中最远的点决定，因为沿线移动时会自动覆盖中间点。 合适的人的成本同样会降低到从 106 到其后缀的最近点。 

k 上的循环考虑所有有效分区，包括一个人处理所有事情的退化情况。 

必须注意边界索引。 当k = 0或k = n时，其中一方没有分配奖品，其成本为零。

 ## 边缘情况

 当只有一个奖项时，算法会评估两个有意义的分割：将其分配到左侧或右侧。 最小值正确地成为距较近起始位置的距离。 

当所有奖品都位于位置 1 附近时，左边的人处理大部分或所有奖品的每次分配都会产生很小的价值，而将它们分配给右边的人会显着增加成本。 该算法自然会选择左重分割，因为它最小化了两侧的最大值。 

当所有奖金接近 106 时，对称行为适用。 分割 k = 0 或较小的 k 值占主导地位，确保合适的人处理大部分工作。 

当奖品均匀分配时，中间分割点可以最大限度地减少两个代理的旅行距离之间的不平衡。 k 上的循环直接捕获这个平衡点，确保不需要贪婪的局部分配。
