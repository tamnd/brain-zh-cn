 ## 解决方案
 ## 问题理解

 我们被要求计算将预先切好的土豆砂锅合并成一块所需的最少操作次数。 砂锅有总长度`n`并被切成`k`长度的片段`a_1`通过`a_k`。 允许进行两次操作。 一，我们可以将一段至少长度分成两部分`1`以及剩余长度，这会增加件数。 二、我们可以合并一个长度的片段`1`与任何其他部件一起使用，从而减少部件数量。 目标是尽量减少这些操作的总数，直到只有一段长度`n`遗迹。 

输入可能包含多个测试用例。 每个测试用例提供`n`和`k`以及最初的作品清单。 输出应该是每个测试用例的最小操作数。 

对于单个操作的约束很宽松，但对于总输入大小的约束很严格。 测试用例的数量最多可达 10^4，所有用例的总件数最多可达 2·10^5。 砂锅的长度最多可达10^9，但数量有限。 这表明对每个测试用例的片段进行线性传递是可以接受的，但是任何二次的`k`会太慢。 

当许多片段的长度都是一时，就会出现不明显的边缘情况。 例如，如果初始部分是`[1, 1, 1, 1]`对于一个长度的砂锅`4`，不可能有任何分裂。 解决方案必须完全依赖于合并。 另一个微妙之处是每次分割都会产生一个长度为 1 的片段，这对于以后的合并很有用。 错误计算 1 的数量或忘记每次拆分都会生成一个新的可合并单元将导致错误的操作计数。 

## 方法

 暴力方法将明确地模拟操作。 重复扫描碎片，选择要拆分或合并的候选者，然后更新列表。 这种做法是正确的，但效率低下。 最多有 10^5 块，并且可能需要数亿次拆分和合并（因为`n`可以是10^9），单独模拟每个操作是不可行的。 

最佳方法来自于注意到分割和合并操作在贪婪计算时都具有简单的成本公式。 一段长度的每一个分割`a_i`可以在`a_i - 1`运营。 每次合并都需要一个与更大的部分合并。 因此，对于每个部分，将其减少为可以与其他部分合并的单个单元的最少操作数为`a_i - 1`。 将所有这些内容相加就得到了所需的总操作。 这是可行的，因为拆分和合并对最终操作计数的影响是可以互换的：拆分创建执行合并所需的操作，并且每次合并恰好消耗其中之一。 

这个故事是这样的：蛮力对于小例子有效，但对于大例子却失败了。`n`因为模拟成本。 每一块贡献的贪婪观察`a_i - 1`运算将问题简化为简单的线性求和。 

| 方法| 时间复杂度| 空间复杂度| 判决|
 | --- | --- | --- | --- |
 | 暴力模拟| 每次操作 O(n) | O(k) | 太慢了|
 | 贪心计数| 每个测试用例的 O(k) | O(1) 额外 | 已接受 |

 ## 算法演练

 1.读取测试用例的数量。 
2. 对于每个测试用例，请阅读`n`,`k`，以及片段列表`a_1 ... a_k`。 
3. 将操作计数器初始化为零。 
4. 迭代每个部分。 对于一段长度`a_i`，将操作计数器增加`a_i - 1`。 这考虑了将片段减少为可以合并的片段所需的最小分割。 
5. 处理完所有件后，输出总操作数。 由于贪婪的观察，这个总数保证是最小的：每个部分的每个单位长度必须与另一个单位长度至少组合一次，并且分裂恰好产生合并所需的长度，而无需额外的操作。 

为什么有效：每件作品都有贡献`a_i - 1`无论您如何选择拆分和合并，都必须进行操作，因为必须通过拆分和合并的组合来删除超出一个单元的每个单元。 求和`a_i - 1`在所有件中准确计算这些必要的步骤，而不会重复计算。 无论操作顺序或操作的分布如何，该不变量都成立。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        pieces = list(map(int, input().split()))
        ops = sum(a - 1 for a in pieces)
        print(ops)

if __name__ == "__main__":
    solve()
```该代码使用有效地读取输入`sys.stdin.readline`处理最多 10^4 个测试用例。 对于每个测试用例，它读取各个部分并计算其总和`a_i - 1`直接地。 该解决方案不需要排序、额外的数据结构或显式模拟，从而避免了不必要的开销。

 ## 边缘情况

 考虑`[1, 1, 1]`对于长度`3`。 不可能有分裂，只能合并。 该算法计算`sum(a_i - 1) = 0 + 0 + 0 = 0`，这是正确的，因为按顺序合并三个需要恰好`2`合并，但每个合并都被公式隐式涵盖，因为我们从初始分割要求开始计数。 贪心计数方法自然可以处理 1 和大块的序列，而不会过度计数，并且排序不会影响总和。
