 ## 解决方案
 ## 问题理解

 我们被要求构造一个从 1 到$n$使得某个表达式最大化。 该表达式是“大”数字（大于或等于$k$）减去所有“小”数字的前缀和（小于或等于$m$）。 排列必须包含从 1 到$n$正好一次。 

每个测试用例的输入是三个整数：$n$（排列的长度），$m$（小数字的阈值），以及$k$（大数的阈值）。 输出是 1 到 的任意排列$n$最大化所有前缀上大数和小数的累积和之间的差异。 

主要限制是$n$可以达到$10^5$，以及总和$n$所有测试用例的最大可达$2 \cdot 10^5$。 这告诉我们，一个$O(n \log n)$或者$O(n)$解决方案是可以接受的，但是$O(n^2)$解决方案会太慢。 

一个不明显的一点是，数字严格介于$m+1$和$k-1$对任何一个总和都没有贡献，因此他们的位置与分数无关。 另一个微妙之处是，过早放置较小的数字会增加惩罚（g(i) 贡献），而过早放置较大的数字会最大化奖励（f(i) 贡献）。 

例如，与$n=5$,$m=2$,$k=5$，一个排列 [5,3,4,1,2] 产生$f(i)$和$g(i)$给出最大差异的值。 像 [1,2,3,4,5] 这样的朴素排列会产生较小的差异，因为小数字出现在大数字之前，从而增加了惩罚。 

## 方法

 蛮力方法是尝试所有$n!$排列、计算$f(i)$和$g(i)$对于每个，并选择最大值。 这在理论上是有效的，因为它可以正确计算任何排列的总和，但即使对于中等排列也是不可行的$n$， 自从$5! = 120$和$10! \sim 3.6 \cdot 10^6$，远低于最大值$n = 10^5$。 

关键的见解是每个数字对最终总和的贡献与其出现的前缀数量呈线性关系。为了最大化 f(i) 贡献的总和，我们应该将所有大于或等于$k$尽早。 为了最小化 g(i) 贡献的总和，我们应该将所有小于或等于$m$尽可能晚。 之间的数字$m+1$和$k-1$可以放在任何地方，因为它们不影响分数。 

因此，最佳排列的构造方法是：首先按降序列出 ≥ k 的数字，然后按任意顺序列出中间的数字，最后按升序列出 ≤ m 的数字。 这确保了在尽可能多的前缀中对 f(i) 贡献最大的数，在尽可能少的前缀中对 g(i) 贡献最小的数。 

| 方法| 时间复杂度| 空间复杂度| 判决|
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 太慢了|
 | 最佳| O(n) | O(n) | 已接受 |

 ## 算法演练

 1.读取测试用例数量$t$。 
2. 对于每个测试用例，请阅读$n$,$m$， 和$k$。 
3. 初始化三个列表：`large`对于数字 ≥ k，`middle`对于 (m, k) 中的数字，以及`small`对于 ≤ m 的数字。 
4. 迭代从 1 到 n 的所有数字：

 - 如果数字≥k，则将其附加到`large`。 
- 如果数字≤m，则将其附加到`small`。 
- 否则，将其附加到`middle`。 
5. 通过连接构造排列`large`按降序排列，`middle`以任何顺序（为简单起见升序），并且`small`按升序排列。 
6. 输出排列。 

为什么有效：将所有 ≥ k 的数字放在前面可以最大化它们对包含它们的每个前缀的贡献。 将 ≤ m 的数字放在末尾可以最大限度地减少它们的贡献。 m 和 k 之间的数字不会影响分数，因此它们的顺序并不重要。 这种策略保证了任何排列都不能获得更高的差异。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m, k = map(int, input().split())
    large = []
    middle = []
    small = []
    for i in range(1, n + 1):
        if i >= k:
            large.append(i)
        elif i <= m:
            small.append(i)
        else:
            middle.append(i)
    permutation = large + middle + small
    print(*permutation)
```该解决方案使用快速读取输入`sys.stdin.readline`，将数字分为三类，并将它们连接起来以使分数最大化。 使用列表运算可以避免差一错误并确保输出是有效的排列。

 ## 边缘情况

 一个棘手的边缘情况是`m+1 = k-1`，意味着只有一个中间数。 为了`n=5, m=2, k=4`，数字是`[1,2,3,4,5]`。 我们的算法放置`[4,5]`（大）先，然后`[3]`（中），以及`[1,2]`（小）最后。 得到的排列`[4,5,3,1,2]`确保早期 f(i) 贡献最大，后期 g(i) 贡献最小，正确处理单例中间数。 这表明即使中间段只有一个元素，该算法也能正常工作。
