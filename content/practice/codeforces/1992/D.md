 ## 解决方案
 ## 问题理解

 我们有一条河流，其行为就像一块线性板`n`细胞。 每个单元要么是圆木形式的安全地面，要么是危险的水，要么是立即失效的鳄鱼瓷砖。 目标是从第一个单元格之前的左岸移动到最后一个单元格之后的右岸。 

运动受到两种独立方式的限制。 当 ErnKor 站在安全表面（即银行或圆木）上时，他最多可以向前跳跃`m`细胞。 当他在水中时，运动变得更加缓慢：他通过游泳一次只能前进一个细胞，消耗的每一个细胞的水都会导致全球极限`k`。 鳄鱼牢房在任何情况下都是禁止着陆的位置。 

关键的困难在于状态的变化取决于我们是在木头上还是在水中。 原木充当安全检查点，跳远会重置“模式”，而水段则在游泳距离方面施加线性成本。 我们必须确定是否存在任何有效的跳跃和游泳序列，可以在不踩到鳄鱼且不超过的情况下到达对岸`k`穿过的水单元总数。 

这些约束表明我们每个测试用例都需要一个线性或近线性的解决方案。 总计`n`所有测试用例最多`2·10^5`，所以任何超过的算法`O(n log n)`总体而言，存在速度太慢的风险。 自从`m ≤ 10`，我们被鼓励在本地处理跳跃可达性，而不是维护大型动态结构。 

当贪婪跳跃忽略了水段和跳跃机会之间的相互作用时，就会出现微妙的失败案例。 例如，总是跳转到最远的可到达安全单元的策略可能会将我们困在一条长水走廊中，该走廊超过了`k`，尽管稍短的跳跃序列可以安全地将水分成更小的部分。 

当原木之间存在长而不间断的水段时，会发生另一种极端情况。 即使存在原木，它们之间的水也可能需要超过`k`如果我们被迫跨过它而没有中间跳跃，则需要游泳台阶。 这是问题的核心平衡行为。 

## 方法

 蛮力方法将明确模拟每个表面位置的每个可能的选择。 从每个日志或银行位置，我们可以尝试所有跳跃距离`1`到`m`，递归地继续该过程，当落入水中时，模拟强制单步游泳，直到到达下一个表面。 这形成了对由位置以及我们当前是游泳还是站立定义的状态的搜索。 

这是正确的，因为它探索所有有效路径，但它会组合爆炸。 每个表面细胞分支为`m`跳跃和水段引入了长时间的强制过渡。 在最坏的情况下，这会退化为原木数量的指数行为，特别是当河流主要是原木并且水流频繁交替时。 

关键的观察是日志将问题划分为多个部分，在每个部分中我们只需要知道我们是否可以跨越它以及它贡献了多少水成本。 由于跳跃的边界为`m ≤ 10`，从任何日志中我们只需要考虑接下来的几个可到达的日志或水入口点，而不是所有的可能性。 

我们可以将该过程建模为贪婪的可达性扫描。 从左岸开始，尝试延伸跳跃范围内最远可到达的位置`m`，同时尊重鳄鱼。 一旦我们降落在水中，我们就会确定地向前游，直到撞到一根圆木或河岸，从而积累水成本。 这将问题转化为在跟踪水消耗的同时保持最远可到达的“表面边界”。 

中心思想是，每当我们在一个表面上时，只有最远的可到达的下一个表面才重要，因为任何中间跳跃都受到严格控制，除非它避免鳄鱼或减少与水的接触。 自从`m`很小，检查到`m`前面的位置就足够了。

 ## 算法演练

 我们模拟从左到右的移动，同时保持两个状态：我们当前的位置和剩余允许的水距离。 

1. 从位置开始`0`（左岸）与`k`剩余允许游泳距离的单位。 河岸是一个安全的表面，所以我们从跳跃模式开始。 
2. 从任何表面位置`i`，尝试跳转到最远的有效位置`j`这样`1 ≤ j - i ≤ m`和`a[j]`不是鳄鱼。 在所有这些候选点中，我们优先考虑最远的可到达有效着陆点，因为较短的跳跃永远不会提高可达性或降低水成本。 
3. 如果范围内不存在有效的着陆面，我们会跳入最近的可能的非鳄鱼水单元。 这是我们故意进入水中的唯一情况，否则我们总是更喜欢原木或河岸。 
4. 一旦我们进入指定位置的水中`i`，我们必须坚定地一步一步地前进。 对于每一步，我们都会递减`k`并检查我们是否撞到了鳄鱼。 如果我们撞到鳄鱼，这条路就无效了。 如果`k`变得消极，我们也会失败。 
5. 游泳时，我们继续游泳，直到到达一根圆木或右岸。 当我们到达原木时，我们返回表面模式并重复跳跃过程。 
6. 如果在任何时候我们到达位置`n+1`，正确的银行，我们接受。 

### 为什么它有效

 正确性取决于表面立场压缩决策这一事实。 从任何表面单元出发，只能在最远的范围内安全着陆`m`很重要，因为任何中间着陆要么会减少剩余范围，要么会增加以后暴露在水中的机会，而无需提供额外的选择。 水段是没有分支的强制路径​​，因此它们的贡献纯粹是累加的，与我们如何到达它们的入口点无关。 这种分离使我们能够贪婪地最大化表面进展，同时确定性地考虑水成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = input().strip()
        
        pos = 0
        water_left = k
        
        # we treat bank at n+1 as implicit safe 'L'
        while True:
            if pos == n + 1:
                print("YES")
                break
            
            # surface: try jump up to m
            nxt = -1
            
            # try farthest valid landing (log or bank)
            for jump in range(1, m + 1):
                np = pos + jump
                if np == n + 1:
                    nxt = np
                elif np <= n and a[np - 1] != 'C':
                    nxt = np
            
            if nxt == -1:
                print("NO")
                break
            
            # if landing is bank, finish
            if nxt == n + 1:
                print("YES")
                break
            
            # if landing is log, move there
            if a[nxt - 1] == 'L':
                pos = nxt
                continue
            
            # otherwise must be water start -> swim
            pos = nxt
            while pos <= n and a[pos - 1] == 'W':
                water_left -= 1
                if water_left < 0:
                    print("NO")
                    break
                pos += 1
            else:
                continue
            break

solve()
```解决方案维护一个指针`pos`代表 ErnKor 当前站立或游泳的位置。 跳转循环扫描至`m`前面的细胞总是保持最远可到达的非鳄鱼位置，这编码了贪婪的表面扩张思想。 

一旦选择了水单元，内循环就会模拟在水中的强制运动，同时递减`water_left`。 这`while-else`结构确保我们只有在内部游泳没有失败的情况下才能继续外部过程。 

该银行被视为虚拟安全单元`n+1`，这简化了边界处理并避免了最后跳转的特殊情况。

 ## 边缘情况

 一个关键的边缘情况是，即使存在到原木的较短跳跃，最佳路径也需要有意进入水中。 在这种情况下，总是偏爱日志的天真贪婪策略可能会失败。 模拟正确地处理了这个问题，因为它只优先考虑跳跃范围内的原木，并且仅在不存在安全表面时才进入水中。 

另一种微妙的情况发生在`k = 0`。 在这里，任何强制游泳都会立即失败。 The algorithm still works because every water transition explicitly decrements`water_left`，第一次减量触发拒绝，符合不允许水遍历的要求。 

最后，当长长的鳄鱼阻挡了所有着陆选项时`m`，扫描正确产生`nxt = -1`，确保立即终止而不尝试无效游泳。
