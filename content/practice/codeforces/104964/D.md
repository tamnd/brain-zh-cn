 ## 解决方案
 ## 问题理解

 我们正在穿过一条在航站楼之间被分成连续路段的道路。 每个路段可以在多个平行车道上行驶，并且每个车道对该路段都有自己的行驶成本。 此外，在任何航站楼都可以在相邻车道之间移动，并且这种车道变换每步的成本是固定的。 

任务是计算从第一个航站楼到最后一个航站楼的最小可能总行程时间。 开始时我们可以选择任何车道，最后我们可以在任何车道结束。 运动总是在终点站前行，但在每个终点站，我们可以选择在继续之前在车道之间横向移动。 

在计算出这个基本最短时间后，我们还必须回答一系列更新。 每次更新都会阻塞单个段上的单个通道，这意味着对于该段，我们不允许使用该通道。 每次此类修改后，我们需要再次重新计算最小行程时间，将所有修改视为当前活动。 

这些约束清楚地表明该结构很大：终端和车道的数量都可以达到一百万，但总输入大小受 N·K ≤ 10^6 限制。 这意味着我们不能承受比预处理输入大小的大致线性时间更糟糕的事情。 但是，最多有 10^6 次更新，这使得每个查询都无法进行任何重新计算。 这促使我们寻求一种解决方案，在预处理阶段之后，每次更新都在接近恒定或对数的时间内处理。 

对于每个查询，在终端和通道上进行简单的动态编程将需要重新计算 N by K 状态表，这立即就太慢了。 

即使在基本问题中，也会出现更微妙的边缘情况：如果 K 很大并且切换成本 X 很小，则最优路径会频繁地在车道之间跳跃，并且任何假设“停留在一条车道中”或仅在段之间进行局部转换的方法都将失败。 

另一种边缘情况是，在多次更新后，段中的所有车道都被阻塞。 幼稚的实现可能仍会尝试通过该段传播值，从而产生错误的有限成本，而实际上该路径是不可能的（无限）。 

## 方法

 该问题可以看作分层网格图上的最短路径：节点是（终端 i，通道 j）。 从 (i, j) 我们可以以成本 A[i][j] 移动到 (i+1, j)，并且在任何终端，我们可以在车道之间水平移动，其成本与车道索引中的距离成正比，即 |j1 - j2| * X。 

蛮力思想是简单的动态规划。 设 dp[i][j] 为在 j 车道到达终点站 i 的最小成本。 从前一航站楼的过渡需要考虑前一行的所有车道，因为在前进之前我们可能已经任意改变了车道。 因此，每个层转换都成为 K 个状态上的完全松弛，每个终端的成本为 O(K²)。 当N达到10^6时，这是完全不可行的。 

关键的观察结果是，水平移动结构是经典的“一维度量转换”：在车道之间移动的成本与距离成正比。 这意味着对于每个终端，我们可以通过两次扫描（从左到右和从右到左）来计算它，而不是使用所有对从头开始重新计算 dp[i][*]，类似于网格 DP 中的距离变换。 

然而，真正的困难是更新。 每个查询都会删除一条边 (i, j) → (i+1, j)，这意味着通道 j 不能用于该段。 这会影响局部成本 A[i][j]，从而影响通过该边的任何最佳路径。

关键的结构洞察是，每个终端到终端的转换仅取决于车道上的本地成本数组，并且车道切换是统一的。 这使我们能够为每个路段维护“跨车道到达和出发的最佳方式”的路段级别摘要，并有效更新。 

我们将问题压缩为为每个段 i 维护一个将传入车道成本映射到传出车道成本的函数。 该函数相对于车道索引是凸的，因为过渡在车道距离上是线性的。 因此，我们可以使用车道上的线段树状结构来维护它，其中每个节点都存储一个凸成本包络。 

每次更新仅修改一个段和一个车道，因此我们更新叶子并重新计算受影响的段树节点，时间复杂度为 O(log K)，而跨 N 个段的全局组合给出了总路径成本。 

这将问题转化为在点更新下维护一系列最小加线性变换。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 每个查询的暴力 DP | O(NK²Q) | O(NK) | 太慢了|
 | 车道上的路段组成 | O((N + Q) log K) | O((N + Q) log K) | O(NK) | 已接受 |

 ## 算法演练

 1. 将每个段 i 解释为函数 Fi，它将终端 i 的成本向量映射到终端 i+1 的成本。 每个 Fi 取决于车道行驶成本 A[i][j]，并强制在行驶路段之前切换车道的能力。 

这种抽象的原因是，除了通过车道成本向量之外，终端到终端的转换是独立的。 
2. 对于每个路段，假设我们以最佳方式到达航站楼 i，计算每个车道的基本输出成本。 这可以使用车道上的两次传递来计算：一次从左到右，一次从右到左，传播车道切换成本 X 的效果。 

此步骤抓住了这样一个事实：行驶一段路段之前的最佳车道选择取决于所有车道，而不仅仅是同一条车道。 
3. 将每个段存储为可应用于大小为 K 的向量的变换，从而生成大小为 K 的新向量。 

关键思想是组合两个段对应于这些变换上的函数组合。 
4. 在 N 段上构建一棵线段树，其中每个节点代表其范围的组合变换。 

这种结构允许我们通过将根变换应用于初始零向量来回答完整的道路遍历。 
5. 要计算初始答案，请将完整组合变换应用于表示从终端 1 开始、所有通道中成本为零的向量。 

结果是终端 N+1 处最终向量的最小值。 
6. 对于每次更新，通过改变A[t][l]来修改受影响的线段，重新计算其局部变换，并向上更新线段树。 

只有 O(log N) 个节点受到影响，并且由于通道扫描，每次重新计算都是 O(K)。 
7. 每次更新后，再次查询根变换并提取最小值作为当前答案。 

这是有效的，因为线段树始终保持所有活动线段的正确组成。 

### 为什么它有效

 核心不变量是线段树中的每个节点都代表其线段范围的精确最短行程变换。 由于每个终端都完全允许车道切换，因此分段之间的成本结构是可分离的：所有跨车道交互都在分段的转换中本地发生，并且不依赖于未来的分段。 正确变换的组合保留了正确性，因为连接的独立层上的最短路径与其最小加运算符的组合完全对应。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**30

class Node:
    def __init__(self, arr):
        self.arr = arr

def merge(left, right, K, X):
    a = left.arr
    b = right.arr

    # propagate left to right using two sweeps
    tmp = [INF] * K

    # left-to-right pass
    best = INF
    for i in range(K):
        best = min(best + X, a[i])
        tmp[i] = best

    # right-to-left pass
    best = INF
    for i in range(K - 1, -1, -1):
        best = min(best + X, a[i])
        tmp[i] = min(tmp[i], best)

    # apply segment cost b
    res = [0] * K
    for i in range(K):
        res[i] = tmp[i] + b[i]

    return Node(res)

class SegTree:
    def __init__(self, data, K, X):
        self.K = K
        self.X = X
        self.n = len(data)
        self.size = 1
        while self.size < self.n:
            self.size *= 2

        self.t = [Node([INF] * K) for _ in range(2 * self.size)]

        for i in range(self.n):
            self.t[self.size + i] = Node(data[i])

        for i in range(self.size - 1, 0, -1):
            self.t[i] = merge(self.t[2*i], self.t[2*i+1], K, X)

    def update(self, idx, new_arr):
        i = idx + self.size
        self.t[i] = Node(new_arr)
        i //= 2
        while i:
            self.t[i] = merge(self.t[2*i], self.t[2*i+1], self.K, self.X)
            i //= 2

    def all(self):
        return self.t[1].arr

def solve():
    N, K, X = map(int, input().split())
    A = [list(map(int, input().split())) for _ in range(N)]

    # initial DP per segment transformed into node vectors
    base = A

    st = SegTree(base, K, X)

    def get_answer():
        arr = st.all()
        return min(arr)

    print(get_answer())

    Q = int(input())
    for _ in range(Q):
        t, l = map(int, input().split())
        t -= 1
        l -= 1

        A[t][l] = INF
        st.update(t, A[t])

        print(get_answer())

if __name__ == "__main__":
    solve()
```该实现是将每个路段表示为每条车道成本的向量。 线段树通过使用两个方向扫描模拟两个相邻线段之间的最佳车道转换来合并两个相邻线段，这对成本为 X 的车道之间移动的效果进行编码。 

该更新只是将分段中的一个车道成本替换为无穷大，从而有效地删除该车道，并重新计算受影响的线段树路径。 

最终的答案始终是根向量中的最小值，因为我们可能在任何车道上完成。

 ## 边缘情况

 当更新阻塞段中唯一可用的通道时，就会出现严重的边缘情况。 在这种情况下，段变换应该有效地为必须经过它的任何路径传播无穷大。 

例如，如果 K=1 并且 A[1][1] 被阻塞，则唯一的路径变得不可能：

 输入：```
2 1 1
5
5
1
1 1
```更新后，路段1无有效车道。 正确的输出是无穷大或哨兵，具体取决于问题约定。 该算法通过将成本设置为 INF 来处理此问题，该成本通过线段树传播并确保根最小值变为 INF。 

另一个微妙的情况是当转换成本 X 大于任何 A[i][j] 时。 然后，最佳路径永远不会切换通道，并且解决方案退化为独立的每通道前缀和。 该算法仍然有效，因为两遍松弛永远不会更喜欢切换。 

最后的边缘情况是交替更新，反复禁用和重新启用通道。 线段树重新计算确保仅局部结构发生变化，并且在查询之间不会持续存在过时的 DP 状态，因为每个节点都被完全重新计算而不是增量调整。
