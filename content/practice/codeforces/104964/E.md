 ## 解决方案
 ## 问题理解

 我们有一个大的矩形网格。 一些网格单元包含一株植物，并且每株植物都有固定的长度。 对于每株植物，我们最多可以选择将其“绑”在四个方向之一：上、下、左或右。 捆绑意味着我们将一段从该单元格的中心直接拉伸到场地那一侧相应的栅栏，消耗沿途的每个单元格。 

关键的几何限制是这些拉伸的段在物理上占据了网格内部的空间。 两个选定的片段在它们经过的任何单元中都不允许重叠，即使是部分重叠。 每个单元格总共可以被最多四个不同的线段穿过，但在单元格的同一方向“四分之一”中不能超过一个线段，这有效地防止两个线段以相同的方向穿过同一单元格。 

每个植物也有长度限制：只有当其长度足以沿该方向到达边界时，它才能被绑在一个方向上。 

任务不是最大化具有复杂几何相互作用的任何东西，而是选择有效连接的最大数量并输出哪些植物被连接以及在哪个方向上。 

网格可以非常大，在所有测试中最多可达一百万个单元，但植物的数量要少得多，总共最多十万个。 这已经排除了任何模拟通过网格的路径或逐个单元检查碰撞的解决方案。 任何依赖于段长度的每单元或每路径遍历都会太慢。 

主要的微妙之处在于，虽然路径看起来像长段，但它们的交互结构非常简单：只有当两个段试图以相同方向穿过同一行或列时才会发生冲突。 幼稚的解释会尝试显式标记每个段的所有访问过的单元格，但这会由于潜在的长路径而立即 TLE。 

朴素模拟的一个典型失败案例是许多工厂都试图走正确的路线。 尽管每个工厂单独有效，但它们的路径严重重叠，并且不尊重全局约束的天真贪婪分配将产生无效的重叠或计数过多。 

例如，在第 1、2 和 3 列有植物的行中，所有植物都试图向右移动，所有路径都经过第 3 列到达边界。 任何在没有全局限制的情况下独立对待每一个的解决方案都会错误地接受所有三个。 

## 方法

 蛮力的想法很简单。 对于每种植物，尝试所有四个方向。 对于每次尝试，模拟逐个单元行走直至到达边界，并检查是否有任何单元已被另一个选定的段占据。 如果没有，接受它并标记所有单元格。 这是正确的，因为它直接执行规则。 然而，每个段可能会遍历O(n + m)个单元格，并且最多有100,000个段，使得最坏情况的复杂度大致为O(s·(n + m))，这是完全不可行的。 

关键的观察结果是，每个有效段在结构上都是单调的：它总是直接到达边界。 这会删除任何分支或路径选择。 每个方向都简化为沿一行或一列的单个间隔约束。 

从 (r, c) 向右延伸的线段占据所有单元格 (r, c)、(r, c+1)、...、(r, m)。 这意味着同一行中的所有右向线段共享该行的后缀，因此其中两个总是重叠。 因此，每一行最多只能贡献一个右行段。 同样的推理对称地适用：每一行最多可以有一个左行段，每列最多有一个上行段，每列最多有一个下行段。

这将整个问题简化为每行和每列的独立选择。 我们不必担心几何重叠，只需检查植物是否可以在给定方向上到达边界，然后每行或每列最多选择一个有效候选者。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟| O(s·(n + m)) | O(s·(n + m)) | O(纳米) | 太慢了|
 | 方向分解| O(s) | O(s) | 已接受 |

 ## 算法演练

 我们独立对待每个方向，并利用冲突永远不会在不同行或列之间交叉的事实。 

1. 对于每种植物，根据其长度计算哪些方向是可行的。 如果位于 (r, c) 的植物的长度至少为 c，则可以向左移动；如果至少为 m − c + 1，则可以向右移动；如果至少为 r，则可以向上移动；如果至少为 n − r + 1，则可以向下移动。这将几何形状转换为简单的阈值检查。 
2. 对于每一行，我们决定是否需要一个向右的线段。 我们扫描该行中的所有植物，并选择任何可以放在右边的植物。 一旦选择，我们就不再需要该行中的另一个右行线段，因为任何第二个线段都会沿着该行的后缀重叠。 
3. 我们对每行向左的线段执行相同的操作，与向右的线段无关。 两者不会干扰，因为它们占据每个小区的不同方向区域。 
4. 对于每一列，我们重复相同的逻辑：如果存在任何有效植物，则最多选择一个上行段和最多一个下行段。 
5. 输出所有选定的作业。 

行或列内的选择顺序并不重要，因为可行性仅取决于每个单元格的固定几何形状，而不取决于先前在其他方向上选择的段。 

### 为什么它有效

 固定行或列中的每个方向都会产生一系列线段，这些线段在边界处共享一个公共端点。 这使得同一方向上的每对线段重叠在线的非空后缀或前缀上。 因此，同一行方向或列方向的任何两个段都会发生全局冲突，而不是局部冲突。 因此，将选择限制为每个（行，方向）和（列，方向）最多一个可以消除所有可能的重叠，同时保留最大值，因为选择多个总是无效的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
out_lines = []

for _ in range(t):
    n, m, s = map(int, input().split())

    row_left = {}
    row_right = {}
    col_up = {}
    col_down = {}

    ans = []

    for _ in range(s):
        r, c, l = map(int, input().split())

        # right
        if l >= m - c + 1:
            if r not in row_right:
                row_right[r] = (c, 'r')

        # left
        if l >= c:
            if r not in row_left:
                row_left[r] = (c, 'l')

        # down
        if l >= n - r + 1:
            if c not in col_down:
                col_down[c] = (r, 'd')

        # up
        if l >= r:
            if c not in col_up:
                col_up[c] = (r, 'u')

    for r, (c, d) in row_right.items():
        ans.append((r, c, d))
    for r, (c, d) in row_left.items():
        ans.append((r, c, d))
    for c, (r, d) in col_down.items():
        ans.append((r, c, d))
    for c, (r, d) in col_up.items():
        ans.append((r, c, d))

    out_lines.append(str(len(ans)))
    for r, c, d in ans:
        out_lines.append(f"{r} {c} {d}")

print("\n".join(out_lines))
```该实现将问题压缩为四个独立的哈希图，每个方向类一个。 每个映射确保我们每行或每列最多存储一个候选者。 关键细节是我们从不模拟路径； 我们仅将长度与到边界的距离进行比较。 

一个微妙的点是，我们永远不需要确保同一行中的左右选择或同一列中的上下选择之间的一致性，因为它们占据每个单元格的不同方向四分之一并且在结构上不冲突。 

## 工作示例

 考虑一个单行示例，其中 n = 1、m = 5，植物位于第 1、3 和 5 列，所有植物的长度都足够大。 

我们处理正确方向的可行性：

 | 植物 (r,c) | l 权利的条件| 接受了对吗？ | 选择|
 | --- | --- | --- | --- |
 | (1,1) | 是的 | 是的 | 第一位候选人 |
 | (1,3) | 是的 | 被忽略 | 已选择|
 | (1,5) | 是的 | 被忽略 | 已选择|

 尽管多个单独有效，但仅保留一个右行线段。 这证明了后缀路径的全局重叠。 

现在考虑一个 n = 4 的列示例，同一列中第 1、2 和 4 行的植物都能够向上生长。 

| 植物 (r,c) | 状态 | 接受了吗？ | 选择|
 | --- | --- | --- | --- |
 | (1,c) | 是的 | 是的 | 第一位候选人 |
 | (2,c) | 是的 | 被忽略 | 已选择|
 | (4,c) | 是的 | 被忽略 | 已选择|

 这显示了基于列的冲突如何反映基于行的冲突。

 ## 边缘情况

 当同一行中的多个植物都符合同一方向时，就会出现极端情况。 该算法只保留一个，这是正确的，因为任何两个这样的段不可避免地会在行的共享后缀或前缀中重叠。 

另一种情况是工厂可以同时满足多个方向。 该算法允许在不同的地图中独立选择。 这是安全的，因为每个方向使用每个单元的不同四分之一，因此单个植物最多可以贡献四个有效部分。 

最后一种情况是网格极其稀疏，每行每列只有一株植物。 在这种情况下，所有约束都消失了，解决方案只是输出所有可行的方向，这表明该算法自然地适应密集和稀疏配置。
