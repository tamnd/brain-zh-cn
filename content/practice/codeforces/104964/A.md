 ## 问题理解

 我们在数轴上给出了三个整数位置，代表三个点。 一个操作让我们选择这些点的有序对，并将一个单位的值从第二个选择的点移动到第一个选择的点。 具体来说，如果我们选择具有值的点$u$和$v$，他们变成$u+1$和$v-1$。 

关键效果是每个操作都保留所有三个值的总和。 因此，所有三点最终相等的唯一方法是最终状态为$(x, x, x)$在哪里$3x = a+b+c$。 这立即暗示了一个必要条件：总和必须能被 3 整除。 

任务是确定这种转换是否可能，如果可以，则计算最少的操作数。 当需要时，我们还必须输出明确的操作序列。 

约束将问题分为两种情况。 当只需要可行性时，数值可以达到$10^9$，这将我们推向纯粹算术或基于不变式的解决方案。 当必须构造操作时，值会缩小到$10^5$，这表明只要操作数量呈线性，构造性模拟就是可以接受的。 

一种简单的方法是模拟任意传输或尝试搜索可能的中间状态。 这会立即失败，因为状态空间不断增长并且操作可以任意交错。 

一个更微妙的失败案例是假设如果总和能被 3 整除，则始终有可能。 这是事实，但前提是我们正确理解如何重新分配点之间的不平衡。 

例如，具体的边缘情况是两个值已经相等但第三个值相距很远$a=1, b=1, c=100$。 即使正确答案存在，尝试两两均衡的粗心策略也可能会振荡或无法有效收敛。 

另一种边缘情况是所有三个值已经相等。 那么就需要零操作，任何算法都必须尽早检测到这一点。 

## 方法

 蛮力的想法是将每个状态视为图中的一个节点，其中每个操作在状态之间转换。 超越各州的 BFS 最终将找到一条通往平等的道路。 然而，状态空间在两个方向上都是无限的，因为坐标是无界整数。 即使限制可达总和也会产生巨大的隐式图，使得这种方法不可行。 

关键的观察结果是，该操作将一个单元从一个坐标移动到另一个坐标，因此系统的行为就像将总质量分布在三个箱子之间。 最终状态必须恰好是每个 bin 中的平均值，因此需要将每个坐标调整为$(a+b+c)/3$。 

我们总是可以贪婪地解决不平衡问题，而不是全局搜索。 如果一个值低于目标，我们必须通过从高于目标的任何值中获取来增加它。 这就产生了从盈余到赤字的确定性单位流动。 每个操作都严格减少与目标配置的总绝对偏差。 

这将问题简化为重复将赤字元素与盈余元素配对，直到所有元素达到平衡。

 ## 算法演练

 1. 计算总和$S = a+b+c$。 如果$S \not\equiv 0 \pmod 3$，立即断定不可能。 这是必要的，因为每个操作都会保留总和。 
2. 计算目标值$x = S / 3$。 这是唯一可能的最终状态。 
3. 根据是否高于、等于或低于，将三个头寸分为盈余、中性或赤字$x$。 这决定了转移的方向。 
4.虽然并非所有值都相同$x$，选择任意索引$i$值低于$x$和任何索引$j$具有上述值$x$，并执行一项操作，从$j$到$i$。 这直接减少了与目标状态的总偏差。 
5. 将每个操作记录为有序对$(i, j)$对应于所选的传输。 
6. 重复直到所有三个值都精确$x$。 由于每个操作至少减少一个单位的不平衡，因此该过程必须终止。 

### 为什么它有效

 不变量是总和保持不变，并且每次操作都保留达到的可能性$(x, x, x)$。 每一步都严格减少数量$|a-x| + |b-x| + |c-x|$，因为我们将一个单位从盈余要素移至赤字要素。 该数量是非负数，并且每次操作都会减少 2（1 从盈余中删除，1 添加到赤字中），因此它最终必须达到零，此时所有坐标都相等$x$。 这保证了移动次数的终止和最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input().strip())
    a, b, c = map(int, input().split())

    arr = [a, b, c]
    s = sum(arr)

    if s % 3 != 0:
        print("No")
        return

    x = s // 3

    ops = []

    def take(i, j):
        arr[i] += 1
        arr[j] -= 1
        ops.append((i + 1, j + 1))

    for _ in range(10**5):
        if arr[0] == arr[1] == arr[2]:
            break

        hi = max(range(3), key=lambda i: arr[i])
        lo = min(range(3), key=lambda i: arr[i])

        if arr[hi] == arr[lo]:
            break

        take(lo, hi)

    if arr[0] == arr[1] == arr[2]:
        print("Yes")
        print(len(ops))
        if t == 1:
            for u, v in ops:
                print(u, v)
    else:
        print("No")

def main():
    solve()

if __name__ == "__main__":
    main()
```该实现首先检查整除条件并隐式计算目标。 这`take`函数完全按照定义应用操作，包括记录有向对。 

循环始终选择全局最小值和全局最大值，这保证了每一步的不平衡性最大程度减少。 这避免了需要对赤字和盈余集进行明确的簿记。 

人工迭代上限是安全的，因为每个操作都会减少总体不平衡，并且在构造性情况下整数值有界，收敛发生在相对于初始扩展的线性时间内。 

一个微妙的点是，我们并没有明确地强制朝着确切的目标值移动，而是始终在最小值和最大值之间。 这已经足够了，因为任何不统一的配置都必须至少有一个严格的最小值和最大值。

 ## 边缘情况

 一种重要的边缘情况是所有三个数字都相等。 该算法必须立即终止而不执行操作。 用于输入`0 0 0`，状态已经满足条件，所以输出为`Yes`零操作。 

另一种情况是两个值相等，而第三个值偏移 3 的倍数。例如`1 1 4`。 该算法重复从 4 向 1 转移，每一步之后，分布都会减小，直到所有值都匹配。 最小-最大策略确保不会发生振荡。 

第三种情况是值已经紧密聚集但不相等，例如`10 11 12`。 从 12 到 10 的单次转换会缩小范围，并在再进行一次平衡步骤后立即实现均匀性。
