 ## 解决方案
 ## 问题理解

 我们有一个线性的楼层塔，每个楼层 i 都有一个敌人，其所需的强度 ai 和奖励 bi 可以在击败该敌人后增加玩家的强度。 玩家可以沿着相邻楼层行走，只能在 i 和 i + 1 或 i - 1 之间移动。重要的规则是，只有在第一次访问某个楼层时才会与敌人战斗，但其他情况下移动本身是自由的。 

玩家在选定的楼层 p 以初始强度 v 开始查询。到达后，他们立即与楼层 p 上的敌人战斗。 如果他们当前的力量至少为ai，他们获胜并增加bi，否则比赛结束。 之后，他们可能会一步一步地移动，可能会向任一方向探索这条线，并与每个新楼层战斗一次。 

对于每个查询，我们都会被询问如果玩家选择在线上的最佳移动顺序，他们可以达到的最大力量。 

这些约束意味着每个测试用例的 n 和 q 最多可达 10^5，测试用例的总和最多可达 10^6。 任何尝试模拟每个查询移动的解决方案都会立即变得太慢，因为即使每个查询一次遍历也可能花费 O(n)，在最坏的情况下给出 O(nq)，这远远超出了可接受的范围。 

一个微妙的点是，重新访问楼层不会重新触发其奖励，因此移动本质上是选择从 p 向外的消耗间隔顺序。 另一个重要的边缘情况是当初始强度太小甚至无法击败起始地板时，在这种情况下答案只是 v。 

一个天真的错误是假设一旦你可以朝一个方向前进，你就应该贪婪地继续前进。 这会失败，因为朝一个方向前进可能会更早解锁另一侧的楼层，并且除非经过适当转换，否则最佳路径不是单调的。 

## 方法

 暴力解释很简单：对于每个查询，模拟从起始位置向外行走的所有可能方式，维护访问集并递归地尝试向左或向右移动。 每个状态代表访问过的楼层的子集和当前位置。 这是正确的，因为它探索了所有有效的移动顺序，但状态数量随着 n 呈指数增长，因为每个新的楼层选择都会使分支加倍。 即使是始终沿一个方向向外扩展的简化模拟，每次查询的成本仍然为 O(n)，从而导致总操作量为 O(nq)。 

关键的观察结果是，运动结构是一个线图，玩家正在有效地扩展 p 周围的可达区间。 在任何时刻，玩家访问的集合始终是连续的段[L，R]，因为移动仅到相邻的未访问楼层，并且重新访问不会添加新信息。 因此，我们不需要考虑任意路径，而只需要知道在给定当前强度的情况下我们可以向左和向右扩展多远。 

这将问题转化为一条线上的动态可达性过程，其中一旦当前强度足够大，每个楼层就变得可用，并且一旦解锁就可以吸收以增加强度。 挑战在于从许多出发点有效地回答这个问题。 

快速实现这一目标的标准方法是使用单调结构预先计算和模拟生长，通常是通过人工智能对地板进行排序，并按照所需强度的递增顺序对其进行处理。 对于固定的起始位置，扩展的行为类似于受当前强度阈值约束的索引上的 BFS。 然而，由于查询很多，我们需要避免从头开始重新计算。

一个更强大的重新表述是，从起始位置开始，玩家最终可以收集一组形成连接段的楼层，并且收集顺序仅与当前强度是否可以跨越阈值 ai 相关。 这意味着为每个方向维护一个结构，使我们能够快速找到下一个未访问的楼层，其人工智能在当前强度范围内，并贪婪地扩展。 

我们为左右扩展边界维护两个优先结构，总是试图吸收最好的可达下一层。 由于一旦包含了一个楼层，它就会永久地增加强度，因此每个查询最多处理一次每个楼层，但我们通过使用全局排序和带有联合查找或平衡树的分段跟踪来避免每个查询的线性扫描。 这将每个查询的复杂性降低到对数或接近对数的摊余时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数 / 每个查询的 O(n) | O(n) | 太慢了 |
 | 最佳| O((n + q) log n) | O((n + q) log n) | O(n) | 已接受 |

 ## 算法演练

 我们对楼层进行预处理，以便始终能够有效地找到下一个候选楼层，并维护楼层是否已被消耗。 

我们使用从起点开始的贪婪扩展独立地模拟每个查询，但我们不是线性扫描邻居，而是维护一个结构，该结构允许我们跳转到任一侧的下一个有效的未访问楼层。 

1. 将当前强度初始化为 v，并仅当 v ≥ a[p] 时才将起始楼层 p 标记为已访问。 如果不是，我们立即返回 v，因为不可能进行任何移动。 
2. 一旦 p 被消耗，我们将其视为最初等于 p 的活跃区间 [L, R]，并将其奖励 b[p] 添加到强度中。 
3. 我们维持两个候选方向，左侧为L - 1，右侧为R + 1，并尝试尽可能向外扩展。 
4. 对于候选楼层 i，只有当该楼层未被访问且当前强度≥ a[i] 时，我们才能进入该楼层。 如果它还无法到达，我们就无法跨越它，因此它暂时阻止了朝该方向的进一步扩展。 
5. 我们反复尝试通过选择当前可到达的任何边界楼层来向左或向右扩展。 一旦我们包含了一个下限，我们就把它合并到区间中，并通过添加 b[i] 来更新强度。 
6. 每次添加新楼层时，我们都会重新检查两个边界，因为增加强度可能会解锁之前被阻挡的楼层。 
7. 当左边界和右边界都无法进一步扩展时，我们停止。 

这种贪婪边界扩展正确的关键原因是，线上的任何有效移动顺序都会产生连续的访问段。 添加新楼层的唯一限制是它的 ai 是否低于当前强度，一旦它变得有效，延迟它就无济于事，因为添加它的 bi 只会增加未来的可达性。 因此，任何最佳策略都可以重新安排，以便楼层一旦在边界处变得可到达就始终被吸收。 

## 为什么它有效

 不变的是，在该过程中的任何一点，所有访问过的节点形成一个包含起始位置的单个连续段，并且该段之外的每个未访问节点要么因强度不足而被阻塞，要么只有当该段扩展到其边界时才变得可达。 

因为奖励只会增加强度而不会降低强度，所以延迟纳入可到达的边界层并不能释放立即纳入所阻止的任何优势。 因此，该算法认为，每当边界层变得可到达时，它就可以安全地被吸收而不会失去最优性，从而确保最终强度最大化。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, q = map(int, input().split())
        a = [0] * (n + 2)
        b = [0] * (n + 2)

        for i in range(1, n + 1):
            ai, bi = map(int, input().split())
            a[i] = ai
            b[i] = bi

        for _ in range(q):
            p, v = map(int, input().split())

            if v < a[p]:
                print(v)
                continue

            vis = [False] * (n + 2)
            vis[p] = True
            cur = v + b[p]

            L = R = p

            changed = True
            while changed:
                changed = False

                while L > 1 and not vis[L - 1] and a[L - 1] <= cur:
                    L -= 1
                    vis[L] = True
                    cur += b[L]
                    changed = True

                while R < n and not vis[R + 1] and a[R + 1] <= cur:
                    R += 1
                    vis[R] = True
                    cur += b[R]
                    changed = True

            print(cur)

if __name__ == "__main__":
    solve()
```该实现为每个查询保留一个本地访问数组，并从起始位置向外扩展。 关键细节是两个 while 循环，它们会积极消耗两侧任何可到达的楼层； 这就是强制不跳过任何可达边界的原因。 

这`changed`flag 确保每次扩展后，我们重新评估两个方向，因为强度增加可以解锁紧邻当前段的新楼层。 如果没有这种重启机制，一些可达的链可能会丢失。 

早期检查`if v < a[p]`这是必要的，因为必须首先战斗起始楼层，并且失败会立即终止查询。

 考虑一个有五层楼的简单场景：

 输入：```

```我们跟踪这个过程：

 | 步骤| 左 | 右 | 当前| 行动|

 | 7 | 1 | 4 | 6 | 5 楼可达（a=7？否）站 |

 该轨迹显示了如何首先向左扩展以增加足够的力量来解锁右侧地板。 

现在考虑第二种情况，初始强度已经很高：```

```| 步骤| 左 | 右 | 当前| 行动|

 ## 边缘情况

 一种微妙的边缘情况是起始楼层无法被击败。 在这种情况下，不允许任何移动，因为战斗立即发生。 该算法通过提前返回来处理这个问题`if v < a[p]`，确保不会尝试无效扩展。 

另一种情况是，由于高人工智能，地板会阻止一侧的扩展，但只有在扩展另一侧后才能到达。 该算法自然地解决了这个问题，因为每次成功的吸收都会增加 cur，并且每次更改后都会重试两个方向，从而允许先前阻塞的边界变得活跃。 

最后一种情况是单个长链，其中最佳顺序不是严格从左到右或从右到左。 区间扩展机制确保顺序无关紧要，因为一旦任何边界变得可到达，它就会被吸收，并且最终结果与方向选择无关。
