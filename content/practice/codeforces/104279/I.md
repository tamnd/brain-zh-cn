 ## 解决方案
 ## 问题理解

 我们有一个包含 15 种动作的游戏系统，其中每个动作根据其指数消耗固定数量的耐力。 动作 1 至 4 各消耗 8 耐力，动作 5 至 10 各消耗 9 耐力，动作 11 至 15 各消耗 10 耐力。 玩家有总体力预算`n`，并且可以执行每种类型的任意数量的操作。 目标是计算有多少种不同的方式可以准确地花费所有`n`耐力，其中一种方式纯粹由 15 个动作中每个动作的使用次数来定义，而不是它们执行的顺序。 

形式上，我们计算线性方程的非负整数解的数量，其中变量被分为具有相同系数的三组：四个变量按 8 加权，六个变量按 9 加权，五个变量按 10 加权。如果任何变量不同，则两个解不同。 

限制条件非常大：`n`最多可达 10^18，并且最多有 10^4 个测试用例。 这立即排除了任何迭代的方法`n`，甚至超过分区方式的数量`n`在朴素的多维 DP 意义上。 任何解决方案必须仅依赖于算术性质`n`和小型固定结构。 

在推理可行性时会出现一个微妙的问题：并非所有`n`是可表示的，因为所有成本都是 1 的倍数，但更重要的是，该结构仅受具有多重性的 8、9 和 10 的硬币组合的限制。 一个天真的想法是独立对待每个动作，但由于多个动作共享相同的成本，因此组合不仅仅是划分，而是重复的组合。 

一个小的边缘案例清楚地说明了结构。 如果`n = 8`，有效的解决方案包括仅使用一次 4 个 8 成本操作中的一个。 这已经给出了 4 种不同的解决方案。 只计算成本组合而忽略多重性的粗心方法将错误地返回 1。 

另一个边缘情况是`n = 9`。 使用 9 成本组有 6 种不同的单操作解决方案，但也有诸如 8 成本操作加上一些不可能的组合之类的组合，这些组合不能被计算在内。 一个简单的背包式 DP 可以处理这个问题，但是速度太慢了`10^18`。 

真正的困难是将“哪个组贡献了多少总成本”与“该成本如何在组内的相同项目之间分配”分开。 

## 方法

 如果我们暂时忽略群内的重数，问题就简化为选择非负整数`A, B, C`这样：`8A + 9B + 10C = n`在哪里：`A`计算 4 个八成本操作的使用总数，`B`在6个九成本行动中，`C`5 个十成本行动中。 

一次`(A, B, C)`是固定的，我们必须分配`A`4 个不同动作的相同用途，类似地`B`跨越 6 个行动，以及`C`跨越 5 个行动。 每个分布都是标准的星条计数。 

所以结构是：外部的三变量丢番图方程，内部的组合数学通过重复组合。 

暴力解决方案将迭代所有可能的解决方案`A`和`B`, 计算`C = (n - 8A - 9B) / 10`，检查整除性和非负性，然后添加分布的二项式系数的乘积。 然而，`A`可以达到`n/8`这是 10^17 的比例，这使得这是不可能的。 

关键的观察是我们只需要求解具有固定系数的线性丢番图方程。 由于仅存在三种硬币类型，因此我们可以通过迭代一个变量并求解另一个变量的模块化条件来减少搜索空间，或者通过在固定一种成本类型后将其视为二变量减少来更干净地减少搜索空间。 

使固定`C`。 然后我们减少到：`8A + 9B = n - 10C`现在对于固定`C`，这变成一个二变量线性方程。 我们可以迭代`A`仅在较小的残差范围内，因为模 9 决定了可行性：`8A ≡ (n - 10C) mod 9`自从`8 ≡ -1 (mod 9)`，这给出了`A ≡ -(n - 10C) (mod 9)`， 所以`A`以模 9 确定。这减少了循环`A`每个最多有一小部分固定数量的候选人`C`。 

最后，`B`被唯一确定一次`A`是固定的。 

我们还必须乘以组合分布：

 分配方式的数量`A`用于 4 件物品是`C(A + 4 - 1, 3)`，

为了`B`分成 6 项是`C(B + 5, 5)`，

为了`C`分为 5 项是`C(C + 4, 4)`。 

自从`C`其本身范围可达`n/10`，我们仍然不能直接迭代它。 所以我们交换策略：而不是修复`C`，我们修复`A`和`B`模约束，并计算`C`直接地。 结构变为：

 迭代`A`在 O(1) 残基类 mod 9 中，然后对于每个`A`，将方程简化为：`9B + 10C = n - 8A`现在我们使用模 10：`9B ≡ (n - 8A) mod 10`自从`9 ≡ -1 mod 10`，我们得到`B ≡ -(n - 8A) mod 10`。 所以`B`是模 10 确定的，我们只需要迭代每个恒定数量的候选者`A`。 

这将每个测试用例的整个问题减少到 O(1) 算术。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| --- | --- | --- |
 | 对 A、B、C 进行暴力破解 | O(n^2) | O(n^2) | O(1) | O(1) | 太慢了|
 | 带有残差枚举的模块化归约 | 每次测试 O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将问题转化为计算约束线性方程的解，然后乘以组合分布。 

1. 将15个变量转换为3个聚合变量`A, B, C`，分别表示成本为 8、9 和 10 的操作总数。 这将等式简化为`8A + 9B + 10C = n`。 
2.对于固定的`A`，计算剩余金额`rem = n - 8A`。 如果`rem < 0`，停止考虑更大的`A`。 这确保了所有后续计算保持有效。 
3. 解决`9B + 10C = rem`。 不要搜索两个变量，而是使用模算术：减少模 10 来确定可能的值`B`。 自从`9 ≡ -1 (mod 10)`，我们推导出一个限制的同余条件`B`到模 10 的单个残基类别。 
4. 枚举所有有效的`B`值与残留条件一致，确保`B ≥ 0`和`9B ≤ rem`。 对于每个有效的`B`, 计算`C = (rem - 9B) / 10`并仅接受整数非负解。 模约束确保每个候选者很少`A`。 
5. 对于每个有效的三元组`(A, B, C)`，计算分布数：`ways(A) = C(A + 3, 3)`对于 4 个相同成本 8 件商品，`ways(B) = C(B + 5, 5)`对于 6 个成本 9 的项目，`ways(C) = C(C + 4, 4)`5 成本 10 件物品。 
6. 将这三个值相乘并累加得到答案模`1e9+7`。 

### 为什么它有效

 关键的不变量是 15 个原始变量的每个有效赋值都唯一对应于一个三元组`(A, B, C)`加上相同成本组中每个聚合计数的独立分布。 线性方程确保不存在超出总数的跨组依赖性，并且组合步骤完全考虑了组内排列。 模块化减少保证了对于每个`A`, 全部可行`(B, C)`对只枚举一次，没有遗漏或重复。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

# precompute nCr up to needed range dynamically via memoized factorials
max_n = 200000  # safe upper bound for combinatorics within constraints

fact = [1] * (max_n + 1)
invfact = [1] * (max_n + 1)

for i in range(1, max_n + 1):
    fact[i] = fact[i - 1] * i % MOD

invfact[max_n] = pow(fact[max_n], MOD - 2, MOD)
for i in range(max_n, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def nCr(n, r):
    if n < 0 or r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

def solve_case(n):
    ans = 0

    maxA = n // 8
    for A in range(0, maxA + 1):
        rem = n - 8 * A
        if rem < 0:
            break

        # B mod 10 constraint from 9B + 10C = rem
        # 9B ≡ rem (mod 10) => -B ≡ rem (mod 10) => B ≡ -rem (mod 10)
        B0 = (-rem) % 10

        # try B = B0 + 10k
        B = B0
        while 9 * B <= rem:
            if B >= 0:
                rest = rem - 9 * B
                if rest % 10 == 0:
                    C = rest // 10
                    if C >= 0:
                        ways = nCr(A + 3, 3)
                        ways *= nCr(B + 5, 5)
                        ways %= MOD
                        ways *= nCr(C + 4, 4)
                        ways %= MOD
                        ans = (ans + ways) % MOD
            B += 10

    return ans

t = int(input())
for _ in range(t):
    n = int(input())
    print(solve_case(n))
```该解决方案预先计算阶乘和逆阶乘，以在恒定时间内评估组合。 主循环迭代可能的值`A`，并且对于每个`A`只有一个很小的算术级数`B`检查从模块化约束导出的值。 每个有效`(A, B, C)`贡献三个星条计数的乘积，对应于在不同技能之间分配相同的动作。 

重要的实现细节是使用模块化归约来限制`B`到单个残基类模 10。如果没有这个，循环就会结束`B`将变成线性`n`，这在给定的规模下是不可能的。 

## 工作示例

 ### 示例 1

 让`n = 8`。 

我们考虑`A = 0`首先，所以`rem = 8`。 

为了`B`，我们计算`B ≡ -8 mod 10 = 2`。 所以`B = 2`是第一个候选人，但是`9B = 18 > 8`，所以不存在解。 

下一个`A = 1`,`rem = 0`。 现在`B ≡ 0`， 所以`B = 0`。 然后`C = 0`。 

| 一个 | 雷姆 | 乙| C | 有效 | 贡献 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 0 | 是的 | C(4,3)*C(5,5)*C(4,4)=4 |

 所以答案是4。 

这与选择四个成本为 8 的操作之一的四个选择相匹配。 

### 示例 2

 让`n = 9`。 

为了`A = 0`,`rem = 9`， 所以`B ≡ -9 mod 10 = 1`。 

尝试`B = 1`， 然后`9B = 9`,`C = 0`。 

| 一个 | 雷姆 | 乙| C | 有效 | 贡献 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 9 | 1 | 0 | 是的 | C(1+5,5)=6 | C(1+5,5)=6 |

 这对应于选择六个成本为 9 的操作之一。 

没有其他`(A, B)`结对工作。 

所以答案是6。 

这些例子证实了基于残基的计数和分离成组合分布的正确性。

 ## 边缘情况

 一个重要的边缘情况是当`n = 0`。 该算法考虑`A = B = C = 0`作为有效的解决方案，组合项的计算结果为`C(3,3) * C(5,5) * C(4,4) = 1`，正确计算空配置。 

另一种情况是当`n < 8`， 例如`n = 7`。 循环结束`A`立即停止于`A = 0`因为`B`候选人总是产生`9B > n`，所以答案正确为0。 

边界情况发生时`n`可以被 10 整除。例如`n = 10`直接承认`C = 1`解决方案，并且模块化条件正确过滤`B = 0`，确保不包含无效的分数分割。
