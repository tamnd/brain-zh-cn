 ## 问题理解

 我们在平面上得到一组没有重复的点，我们需要计算通过选择其中四个点作为顶点可以形成多少个矩形。 关键的几何条件是矩形可以有任何方向，而不仅仅是轴对齐的方向，因此我们正在寻找由点的子集形成的任意欧几里德矩形。 

平面上的矩形完全由它的两个对角相对的顶点决定。 如果我们固定两个点作为对角的候选点，它们将定义一个将是矩形对角线的线段。 其余两个顶点必须位于所有四个点形成相等的对角线和直角的位置，这意味着强对称约束。 

输入大小 n 最多为 1000。简单的 O(n^4) 四元组枚举太慢，因为在最坏的情况下它会检查 10^12 组合的顺序。 即使 O(n^3) 方法也是边界，但 O(n^2 log n) 或 O(n^2) 解决方案是可以接受的。 

一个微妙的问题是计数过多。 每个矩形都有两条对角线，如果我们不小心，根据我们选择的对角线对，同一个矩形将被计算多次。 

没有像共线性限制这样的特殊病态约束，但简并性问题很重要：任何依赖斜率的方法都必须仔细处理垂直线、浮动精度或标准化。 整数几何是优选的。 

## 方法

 蛮力的想法是尝试每个四边形点并检查它们是否形成矩形。 对于四个点，我们可以验证所有成对距离是否与矩形结构匹配，或者边缘之间的向量是否垂直。 这在概念上很简单：计算距离或点积并测试矩形条件。 

然而，这种方法的扩展性很差。 大约有 n^4 / 24 个四元组，在 n = 1000 时大约需要 10^11 次检查，每次检查都需要不断的工作。 即使使用非常快的算术，这也是不可行的。 

关键的结构观察是每个矩形都有两个对角线对角，其中点相同。 如果我们将任何一对点作为潜在的对角线端点，则该对点唯一地确定中点和对角线长度的平方。 对于有效的矩形，必须有另一对不同的点共享相同的中点和相同的对角线长度。 这两对一起恰好形成一个矩形。 

这减少了从搜索四元组到对点对进行分组的问题。 每对都提供一个由中点和平方距离组成的签名。 计算有多少个矩形对应于重复的签名成为所有 O(n^2) 对的频率计数问题。 

如果特定签名出现 k 次，意味着 k 个不同的对共享相同的中点和对角线长度，则每个矩形对应于选择这些对中的两个。 因此，该组贡献的矩形数量为 C(k, 2)。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解四倍 | O(n^4) | O(n^4) | O(1) | O(1) | 太慢了|
 | 按中点和距离对分组 | O(n^2 log n) 或 O(n^2) | O(n^2) | O(n^2) | 已接受 |

 ## 算法演练

 我们将把每对点转换为潜在矩形对角线的规范表示，然后计算每个表示出现的频率。

1. 迭代所有无序点对 (i, j)。 对于每一对，计算线段 ij 的中点，但为了避免浮点运算，请将其表示为双倍中点 (xi + xj, yi + yj)。 这完全避免了分裂并保留了唯一性。 
2. 计算两点之间的平方距离：dx^2 + dy^2。 这确保了具有相同对角线长度的对在不使用平方根的情况下正确分组。 
3. 将这两个值组合成一个键。 该键代表潜在的矩形对角线类。 同一矩形的两条不同对角线始终具有相同的中点和相同的平方长度，因此它们映射到相同的键。 
4. 使用哈希映射来计算每个密钥有多少对产生。 
5. 处理完所有对后，迭代所有键。 对于每个频率 k，将 k * (k - 1) / 2 添加到答案中。 这计算了我们可以选择形成矩形的两条对角线的有多少种方式。 
6. 输出累加和。 

### 为什么它有效

 每个矩形都有两条对角线。 这些对角线共享相同的中点和长度，因此它们产生相同的密钥。 相反，任何两对具有相同中点和相等长度的不同点必须形成矩形的对角线，因为中点条件强制对称性，而相等长度确保一致的缩放。 因此，每个矩形恰好对应于一对无序的相等键，并且对每组内的键对组合进行计数时，每个矩形恰好计数一次。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    from collections import defaultdict
    cnt = defaultdict(int)

    for i in range(n):
        x1, y1 = pts[i]
        for j in range(i + 1, n):
            x2, y2 = pts[j]

            mx = x1 + x2
            my = y1 + y2
            dx = x1 - x2
            dy = y1 - y2
            dist2 = dx * dx + dy * dy

            cnt[(mx, my, dist2)] += 1

    ans = 0
    for k in cnt.values():
        ans += k * (k - 1) // 2

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案构建所有 O(n^2) 对，并仅使用整数算术对每对进行编码。 中点被加倍存储，这样可以避免分割并保持分组准确。 平方距离确保旋转不变性并避免浮点精度问题。 

哈希图累积每个潜在对角线签名出现的次数。 最后的组合步骤将计数转换为矩形计数。 

一个微妙的点是，使用原始中点作为分数需要理性标准化； 加倍就完全避免了这种情况。

 ## 边缘情况

 一个关键的边缘情况是当许多对共享相同的中点但并非所有对都形成矩形时。 该算法可以正确处理这个问题，因为仅靠中点是不够的； 平方距离也包含在密钥中。 

例如，考虑点 (0,0)、(2,0)、(1,1)、(3,1)。 对 (0,0)-(3,1) 和 (2,0)-(1,1) 分别共享中点 (3,1) 和 (3,1)？ 不，中点不同，因此它们不会碰撞。 这表明中点加距离配对可以防止意外分组。 

另一种边缘情况是多个矩形重叠或共享顶点。 计数公式仍然有效，因为它独立地计算对角线对组合，并且每个矩形恰好对应于其对角线组内的一个这样的对角组合。
