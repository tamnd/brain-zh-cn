 ## 解决方案
 ## 问题理解

 我们收到一系列输入请求。 每个请求都表示由整数标签标识的某个键应该被重复按下给定的次数。 如果我们忽略所有硬件问题，我们将简单地累加每个键所需的按下总数。 

问题的症结在于键盘故障。 如果连续按下某个键至少 k 次，则任何进一步尝试按下同一键的操作都会立即无效。 换句话说，连续按下同一个按键 k 次后，键盘将进入该按键的阻塞状态。 要从这种状态恢复，我们只有两个选择：要么切换到另一个键（这会打破连续的连续状态），要么故意按同一个键 k 次以重置机制。 

尽管整个过程是交互式的并且依赖于顺序，但我们要求解决的任务并不是模拟打字过程本身。 相反，在最优地解决所有约束之后，我们只需要输出每个键在最终有效策略中实际按下的次数。 因此，输出是每个键的按下频率摘要，在整个最佳打字计划中汇总。 

输入描述了 n 个片段，每个片段贡献了目标文本中关键 ai 的两次连续出现。 n 最大为 10^5 的约束意味着我们必须在线性或近线性时间内处理段。 ai、bi、k 的值可能很大，bi 和 k 最大可达 10^9，因此我们无法模拟单独的按键操作。 任何显式扩展分段或对每台印刷机进行建模的解决方案都会太慢，在最坏的情况下可能需要多达 10^14 次操作。 

具有相同密钥的连续段会产生一个微妙的问题。 如果我们通过求和来简单地合并它们，我们隐含地假设我们总是可以连续输入它们而不会触发阻塞行为。 然而，如果累积的运行跨越 k 的倍数，键盘机制会强制重置。 简单地聚合每个键的 bi 的粗心解决方案将忽略这些重置，并根据解释进行多计数或少计数。 正确的推理必须考虑不同键之间的转换和强制重置如何破坏运行。 

第二种微妙的情况是当 k 等于 1 时。在这种情况下，除非我们不断重置，否则每两次连续按下同一键都不会产生任何效果，这实际上使得在不不断交替或重置的情况下连续重复变得不可能。 任何算法都必须正确处理这种退化机制。 

## 方法

 暴力视图实际上是逐段模拟打字，并在每个段内模拟每次按键，同时跟踪活动键的当前连续长度。 每当连续达到 k 次时，我们要么切换，要么执行 k 次按下的重置。 这个模拟很简单，也忠实地遵循规则，所以是正确的。 然而，每个段可能需要 O(bi) 运算，并且由于 bi 可以达到 10^9，所以这立即变得不可行。 即使总的来说，模拟操作的总量也可能会超出任何可接受的限度。 

关键的观察是，唯一重要的状态是当前密钥和该密钥的当前条纹长度。 同一键的不同段可以合并，但它们可能会被其他键打断。 我们可以用大小为 k 的块进行推理，而不是模拟每次按下。 每次我们连续连续按下同一键 k 次，我们从概念上讲就会消耗一个“块”并重置连续行为。

这将问题转化为，对于每个键，维护它在全局打字过程中贡献了多少个大小为 k 的完整块，同时正确地考虑了键之间的转换如何破坏连续性。 关键的简化是，尽管该过程是连续的，但在考虑了我们被迫重新启动条纹结构的频率后，最终答案仅取决于每个键的总有效贡献。 

一种更结构化的看待方式是，每个键独立累积贡献，每次我们完成 k 次连续按下，我们就有效地消除了未来按下同一键的阻塞约束。 这意味着每个键的最终计数取决于我们可以将其总需求打包到大小为 k 的组中的次数，以及在中断中幸存下来的剩余部分贡献。 

因此，我们将问题简化为维护部分累积的全局结构并定期刷新已完成的块。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(总bi) | O(1) | O(1) | 太慢了 |
 | 基于区块的积累 | O(n) | O(不同键的数量) | 已接受 |

 ## 算法演练

 我们维护每个密钥当前被“输入”系统的次数的运行累积，以及一个全局结构，确保我们隐式地遵守 k-streak 规则，仅在被迫时才最终确定 k 倍数的贡献。 

1. 读取所有段并按顺序处理它们，将每个 (ai, bi) 视为将出现的键 ai 添加到正在进行的打字流中的请求。 
2. 维护一个映射 cnt，其中 cnt[x] 存储迄今为止分配给键 x 的有效完成按下的总数。 还维护一个运行计数器 cur_key 和 cur_streak 来描述当前活动密钥以及它已连续扩展的次数。 
3、处理段(a,b)时，首先检查a是否等于cur_key。 如果是这样，我们将继续相同的连续，因此我们只需将 cur_streak 扩展 b。 如果 cur_streak 达到或超过 k，我们会重复从中提取大小为 k 的完整块，将每个完整块的 k 添加到 cnt[a] 中，并将余数保留为新的 cur_streak。 
4. 如果 a 与 cur_key 不同，则该条纹被破坏。 我们将 cur_key 重置为 a，将 cur_streak 重置为 b。 这个中断至关重要，因为它保证我们永远不会错误地合并不同的键。 
5. 每次更新后，我们再次从 cur_streak 中提取尽可能多的完整 k 块，并将这些贡献添加到 cnt[cur_key] 中。 这对键盘规则进行了建模，即只有大小为 k 的完整条纹才能导致状态转换。 
6. 处理完所有段后，cur_streak 可能仍包含从未形成完整 k 块的剩余部分。 该余数不会触发阻塞，直接添加到 cnt[cur_key] 中。 
7. 最后，按升序输出所有key及其对应的cnt值。 

关键不变量是，在任何时候，cur_streak 都表示当前密钥运行的后缀，尚未解析为完整的 k 块贡献。 所有完成的 k 大小的块都已移至 cnt 中，因此我们不会重复计算或丢失贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    
    cnt = {}
    
    cur_key = None
    cur_streak = 0
    
    def flush_blocks(key, streak):
        full = streak // k
        rem = streak % k
        cnt[key] = cnt.get(key, 0) + full * k
        return rem
    
    for _ in range(n):
        a, b = map(int, input().split())
        
        if cur_key == a:
            cur_streak += b
        else:
            if cur_key is not None:
                cur_streak = flush_blocks(cur_key, cur_streak)
            cur_key = a
            cur_streak = b
        
        cur_streak = flush_blocks(cur_key, cur_streak)
    
    if cur_key is not None:
        cur_streak = flush_blocks(cur_key, cur_streak)
        cnt[cur_key] = cnt.get(cur_key, 0) + cur_streak
    
    items = sorted(cnt.items())
    print(len(items))
    for c, d in items:
        print(c, d)

if __name__ == "__main__":
    solve()
```该实现遵循维护单个活动运行的思想。 辅助函数`flush_blocks`从当前 streak 中提取所有完整的 k 长度块并将它们推入全局计数器，仅留下剩余部分未解析。 这可以避免模拟单独的按键操作。 

关键的微妙之处在于，在切换键时和每个段扩展之后都必须进行刷新，否则我们将冒着积累大于 k 的条纹而无法提取其全部贡献的风险。 最终冲洗确保剩余的部分运行不会丢失。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个段被处理一次，并且每次刷新都是每个键更新的恒定时间算术 |

 该算法在线性时间内处理多达 10^5 个段，并且仅存储每个键的聚合计数，这很容易满足内存限制。

    from collections import defaultdict

    cnt = defaultdict(int)
    
    cur_key = None
    cur_streak = 0
    
    def flush(key, streak):
        full = streak // k
        rem = streak % k
        cnt[key] += full * k
        return rem
    
    for _ in range(n):
        a, b = map(int, input().split())
        if cur_key == a:
            cur_streak += b
        else:

            cur_streak = b

 ## 边缘情况

 一个关键的边缘情况是当单个段远大于 k 时。 在这种情况下，算法会在一次更新中重复提取完整块。 例如，当 k = 4 且输入 (1, 10) 时，条纹变为 10，这会立即将 8 冲入 cnt[1] 并留下 2 作为余数。 该代码通过一次算术运算来处理这一问题，因此避免了任何每次按下的模拟。 

另一个重要的情况是小段按键之间的频繁切换。 例如，k = 3，输入为 (1,1)、(2,1)、(1,1)、(2,1)。 这里没有段单独达到 k，但正确性取决于永远不会跨不同键进行合并。 该算法在每次切换时重置 cur_streak，因此不会发生无效分组，并且所有贡献在最终聚合之前都保持较小的余数。 

最后一个微妙的情况是最后一个键具有非零余数。 由于未来的段无法触发刷新，因此最后的添加步骤确保此剩余部分仅保留一次，从而避免尾随贡献的无声丢失。
