 ## 解决方案
 ## 问题理解

 我们被赋予了一个树状结构的王国，这意味着有 n 个城市由 n − 1 条道路连接，并且任意两个城市之间只有一条简单的路径。 其中一些城市被标记为重要，有些城市驻有军队。 

每个部队根据邻近度“覆盖”重要城市：对于任何重要城市，我们计算其到每个部队的距离，并将其分配给距离最小的部队。 如果多支部队的最短距离相同，则认为该重要城市受到所有部队的保护。 

这会产生双向计数问题。 对于每个部队，我们想知道它最终最接近多少个重要城市。 对于每个重要城市，我们想知道有多少军队与它最接近。 

关键结构是所有距离都是树上的最短路径距离，因此它们的行为类似于具有唯一路径的标准图距离。 

这些约束高达 200,000 个节点，这立即排除了任何独立计算每个部队到每个重要城市的距离的解决方案。 一种幼稚的方法会尝试从每个部队运行 BFS 或 DFS 之类的方法，这在最坏的情况下将花费 O(mn) ，并且当 m 和 n 都很大时明显超出限制。 即使成对计算距离也太慢，因为每个距离查询都是 O(n)。 

第二个天真的想法是从所有部队运行多源 BFS 并记录每个节点最近的部队。 这部分实际上是可行的，但复杂的是我们只关心重要的节点，并且还需要平局计数，这会破坏简单的单标签传播，除非仔细处理。 

一些微妙的案例暴露了幼稚推理的失败之处。 考虑一个线树 1-2-3-4-5，部队位于 1 和 5，重要城市位于 3。距离是对称的，因此两支部队最近，应该被计算在内。 选择第一个发现的来源的贪婪分配会错误地将其仅分配给一个部队。 当一支部队直接占据一座重要城市时，就会出现另一个问题：即使其他城市同样靠近，该城市也只能分配给该部队，因为距离零主宰一切。 

因此，核心困难是通过连接感知维持正确的多源最短距离，同时还能够仅在重要节点上有效地聚合结果。 

## 方法

 对于每个重要城市，暴力方法使用树上的 BFS 或 DFS 计算其到每个部队的距离。 由于树上的每个距离计算都是 O(n)，并且我们对 k 个重要城市和 m 个部队进行计算，因此仅用于距离评估就变成了 O(km)，在最坏的情况下退化为 O(n²)。 即使使用预处理将每个距离查询优化为 O(1) 也无济于事，因为我们仍然需要对每个重要节点的所有部队进行比较。 

问题的结构表明要颠倒视角。 我们可以同时传播来自部队的信息，而不是询问“对于每个重要城市，哪支部队最近”。 树上的多源 BFS 允许我们同时计算与所有部队的最短距离。 然而，我们还必须保留哪些部队达到了最短距离。 

关键的观察结果是，关系可以在等距离层上局部解决。 如果我们运行一个 BFS，其中每个状态不仅包含距离，还包含部队来源的身份，那么每当我们尝试放松距多个源相同距离的节点时，我们就可以检测到冲突并对其进行计数。 

一旦每个城市都知道了最接近的部队集合，剩下的就是纯粹的聚合：对于每个重要城市，增加所有最近的部队，并为每个重要城市增加其平局计数。 

树结构确保 BFS 足够，因为所有边都具有相同的权重。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力（每个重要城市 BFS/DFS 对所有部队）| O(n²) | O(n) | 太慢了 |
 | 具有关联跟踪功能的多源 BFS | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们最初将每个部队视为 BFS 源，但我们必须单独区分它们，而不是将它们合并为单个超级源。 

1. 构建树的邻接表。 这允许 O(1) 遍历邻居以进行 BFS 扩展。 
2.初始化一个距离数组`dist[node]`无限和一个容器`best[node]`它将存储最接近的部队集合或平局计数的压缩表示。 
3. 将所有部队推入 BFS 队列作为初始状态，距离为 0，并用其部队 ID 标记每个条目。 对于每个部队节点，将其最佳源集设置为仅包含其自身。 
4. 按照标准方式运行BFS。 扩展状态时`(node, troop)`对于距离 d，我们尝试访问所有邻居。 
5. 如果尚未访问邻居，我们为其指定距离 d + 1 并继承当前部队作为其唯一的最接近候选者。 
6. 如果已经在距离 d + 1 处到达了邻居，我们检测到平局情况：这意味着另一支部队以相同的最短距离到达了同一节点。 在这种情况下，我们不会覆盖现有的分配，但我们记录该节点由多个部队争夺。 
7. BFS 完成后，每个节点都知道一个最近的部队或一组相连的最近的部队。 
8.现在我们处理重要的城市。 对于每个重要城市，我们都会增加其最接近集合中每个部队的答案。 我们还为该城市增加了一个计数器，等于其最接近的集合的大小。 

一个关键的微妙之处是确保 BFS 按正确的距离顺序处理节点，这样我们就不会错误地将较长的路径指定为最佳路径。 队列保证增加距离层。 

### 为什么它有效

 BFS 不变量是，当第一次发现一个节点时，它是在距至少一个群体尽可能最小的距离处发现的。 相同距离上的任何后续发现都对应于平局，而不是更短的路径，因为 BFS 保证了不递减的距离扩展。 由于所有边都具有相同的权重，因此第一次到达节点时会固定其最短距离，并且任何等距离到达都与替代的最佳源完全对应。 这保证了分配和平局计数的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque, defaultdict

def solve():
    n, m, k = map(int, input().split())
    p = list(map(int, input().split()))

    adj = [[] for _ in range(n + 1)]
    for i, parent in enumerate(p, start=2):
        adj[i].append(parent)
        adj[parent].append(i)

    troops = list(map(int, input().split()))
    important = list(map(int, input().split()))

    INF = 10**18
    dist = [INF] * (n + 1)

    owner = [[] for _ in range(n + 1)]

    q = deque()

    for t in troops:
        dist[t] = 0
        owner[t] = [t]
        q.append(t)

    while q:
        v = q.popleft()
        for to in adj[v]:
            nd = dist[v] + 1
            if dist[to] == INF:
                dist[to] = nd
                owner[to] = owner[v][:]
                q.append(to)
            elif dist[to] == nd:
                # tie: merge sets (small optimization is not needed conceptually)
                for x in owner[v]:
                    if x not in owner[to]:
                        owner[to].append(x)

    troop_ans = [0] * (n + 1)
    city_ans = [0] * (n + 1)

    for c in important:
        city_ans[c] = len(owner[c])
        for t in owner[c]:
            troop_ans[t] += 1

    print(*[troop_ans[t] for t in troops])
    print(*[city_ans[c] for c in important])

if __name__ == "__main__":
    solve()
```BFS 是通过所有部队初始化的单个队列来实现的。 每个节点都带有最近的部队所有者的列表。 当第一次到达节点时，它会从其父节点继承所有者列表。 当距离相同时，我们会合并所有权列表。 

关键的实现细节是避免过早覆盖`owner[to]`。 我们仅在第一次访问时分配一次，并且仅在等距离重访时扩展它。 这确保严格较长的路径不会影响结果。

 ## 边缘情况

 一个重要的边缘情况是部队直接部署在一座重要城市上。 在这种情况下，它的距离为零，并且没有其他部队可以击败它，除非另一个部队也在同一节点上，这是输入约束所禁止的。 BFS 将该节点初始化为距离 0，因此它始终是唯一的最近源，除非其他地方出现相同距离的平局。 该算法正确地将该节点的所有者设置为该部队。 

另一个边缘情况是一棵完全平衡的树，其中一座重要的城市正好位于两支部队的中间。 BFS 从两侧以相同的距离到达它，因此两支部队都出现在其所有者列表中。 这是通过等距离合并步骤处理的，确保两个贡献都被计算在内。 

第三种边缘情况是重要城市的叶节点远离除一支部队以外的所有部队。 BFS 保证只有最近的路径首先到达它，并且不会引入平局，因为所有替代路径都严格更长。
