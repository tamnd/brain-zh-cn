 ## 解决方案
 ## 问题理解

 我们得到了几个独立的测试用例。 在每个测试用例中，我们都在第一象限中的网格上工作。 我们收到的每个线段都位于一条 45 度对角线上，因为每个线段的端点都满足相同的值$x + y$。 这意味着每个段都被限制从一个点移动$(x_1, y_1)$到另一点$(x_2, y_2)$同时保持在同一条对角线上，严格向右和向下移动。 

从几何角度来看，每个这样的线段都追踪网格中一条固定对角线的一部分。 不同的线段可能位于不同的对角线上，具体取决于它们的$x + y$价值。 

每个测试用例需要两件事。 首先，我们必须确定任何单位网格单元的对角线是否被多次遍历。 由于每个晶胞恰好贡献一个对角线段（相同的斜率方向），因此这一条件相当于确保沿着每条固定的对角线，绘制的线段不会以导致线上任何点被多次覆盖的方式重叠。 

其次，我们必须计算所有绘制线段的总长度，但问题要求将该总长度除以 2。每个线段的贡献仅取决于其水平位移，因为垂直位移由对角线约束确定。 

约束允许最多$10^5$每个测试用例分段，最多 10 个测试用例。 这立即排除了任何二次成对重叠检查。 甚至一个$O(n \log^2 n)$如果使用大量常数来实现，每个测试用例的方法将是边缘的，所以我们应该瞄准$O(n \log n)$或每个测试用例更好。 

如果我们忽略按对角线分组，就会出现微妙的失败情况。 例如，考虑细分：$(0,1)\to(1,0)$和$(1,2)\to(2,1)$。 它们位于不同的对角线上，因此它们永远不会相互作用，并且对它们进行重叠检查是没有意义的。 一种简单的方法，通过以下方式对全球所有细分进行排序$x_1$会错误地比较它们，并可能报告错误的重叠。 

如果我们仅检查端点，则会出现另一种失败情况。 同一对角线上的两个线段可能不共享端点，但线段内部仍部分重叠，这将违反条件。 

## 方法

 暴力方法会比较位于同一对角线上的每一对线段。 对于每一对，我们将检查它们在那条线上的间隔是否与正长度相交。 这需要$O(n^2)$最坏情况下的比较，当$n = 10^5$。 即使每个对角线受到限制，单个对角线仍然可以包含几乎所有线段。 

关键的观察是，每个线段只是一维线上的一个区间，由$c = x + y$。 一旦我们按这个值对片段进行分组，问题就变成了每组的经典间隔重叠检测问题。 我们只需要对每个组内的间隔进行排序，并验证它们不会在端点之外相交。 

第二个任务，计算总绘制长度的一半，简化了，因为每个线段都贡献了其水平跨度$(x_2 - x_1)$到所需的答案。 将所有段中的这些值相加即可直接得出最终结果。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力配对检查|$O(n^2)$|$O(n)$| 太慢了 |
 | 按对角线排序并检查间隔 |$O(n \log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

首先，我们按值对段进行分组$c = x + y$。 这是线段所在对角线的标识。 每个片段都属于一个这样的组。 

其次，在每个组内，我们将每个段视为一维区间$[x_1, x_2]$， 自从$y$唯一确定的是$x + y = c$。 

然后我们按左端点对这些间隔进行排序$x_1$。 排序可确保如果存在任何重叠，它必须按此顺序出现在连续间隔之间。 

接下来，我们扫描排序后的区间并维护迄今为止到达的最右边的点。 如果我们遇到一个新的区间，其起点严格小于当前的右边界，我们会立即检测到重叠并将答案标记为无效。 如果起点等于边界，则这是允许的，因为端点接触并不意味着重复覆盖。 

同时，我们通过添加来累积每个分段对最终答案的贡献$x_2 - x_1$。 

最后，我们输出是否违反重叠条件以及计算出的总和。 

正确性来自于将每条对角线简化为一维线。 在这样的线上，任何重复的覆盖范围都必须按排序顺序显示为区间交集。 由于排序保留了潜在重叠间隔的邻接性，因此单个线性扫描足以检测所有违规。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        groups = defaultdict(list)
        total = 0
        ok = True

        for _ in range(n):
            x1, y1, x2, y2 = map(int, input().split())
            c = x1 + y1
            groups[c].append((x1, x2))
            total += (x2 - x1)

        for c, segs in groups.items():
            segs.sort()
            r = -1
            for l, rr in segs:
                if l < r:
                    ok = False
                    break
                r = max(r, rr)
            if not ok:
                break

        print("YES" if ok else "NO")
        print(total)

if __name__ == "__main__":
    solve()
```该解决方案首先构建一个由对角标识符键控的字典$x+y$。 每个存储的条目都减少到一个间隔$x$，因为对角线约束使得$y$多余的。 重叠检查仅在排序后的每个桶内执行。 

运行总和在输入解析期间立即累积，因为每个段独立贡献$x_2 - x_1$。 这避免了以后需要重新访问片段。 

一个微妙的点是我们允许相邻的间隔$l = r$。 这对应于在端点处接触的线段，而没有任何内部点的双重覆盖，这在问题条件下是有效的。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    def solve():
        T = int(input())
        out = []
        for _ in range(T):
            n = int(input())
            g = defaultdict(list)
            total = 0
            ok = True
            for _ in range(n):
                x1,y1,x2,y2 = map(int,input().split())
                c = x1+y1
                g[c].append((x1,x2))
                total += x2-x1

            for segs in g.values():
                segs.sort()
                r = -1
                for l,rr in segs:
                    if l < r:
                        ok = False
                        break
                    r = max(r, rr)
                if not ok:
                    break

            out.append(("YES" if ok else "NO") + "\n" + str(total))
        return "\n".join(out)

    return solve()

 ## 边缘情况

 一个棘手的情况是线段仅在端点处接触。 例如，$[0,2]$和$[2,5]$在同一条对角线上不违反条件，因为没有单位点被覆盖两次。 该算法处理这个问题是因为它允许相等$l = r$不会触发失败，并且仅在以下情况下标记严格重叠$l < r$。 

另一种情况是所有线段位于不同的对角线上。 即使它们的投影在全局 x 阶上重叠，它们也是独立的。 分组依据$x+y$确保它们永远不会干扰，并且扫描永远不会比较不相关的间隔。 

最后一个微妙的情况是大输入，其中所有段共享相同的对角线。 在这种情况下，该算法退化为单个排序间隔扫描，该扫描仍然运行在$O(n \log n)$由于排序并保持在限制范围内。
