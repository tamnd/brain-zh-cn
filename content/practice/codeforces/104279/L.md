 ## 解决方案
 ## 问题理解

 我们有一棵有 n 个顶点和 n − 1 个无向边的树。 任务不是输出边本身或重建邻接列表，而是为每个顶点 i（从 1 到 n - 1）分配一个伙伴顶点 pi，使得对 (i, pi) 是给定的树边之一。 

换句话说，对于除最后一个顶点之外的每个顶点，我们必须从树中选择一个邻居并将其写下来作为其分配值。 唯一的要求是所选对必须对应于树中的现有边。 

约束 n ≤ 100000 意味着树可以很大，并且任何解在 n 中都必须是线性的或接近线性的。 对于每个顶点尝试搜索边或测试连通性的二次策略立即就太慢了。 即使每个节点重复 BFS，在最坏的情况下也会导致大约 O(n^2) 的行为，这远远超出了可接受的限制。 

解释中的一个微妙点是树是无向的，但输出引入了一种类似方向的结构：每个顶点 i 恰好选择一个邻居 pi。 这本身并不是任意的； 它必须与树结构一致，这意味着 pi 必须与 i 相邻。 

一个天真的错误是假设我们必须指定一个全局方向或​​产生一个扎根的结构。 那不是必需的。 另一个错误是认为答案在某种意义上必须是唯一的或最佳的； 任何有效的分配都会被接受。 

经常混淆实现的一种边缘情况是树是一条简单路径。 例如，如果树是 1-2-3-4，则有效输出包括 p1 = 2、p2 = 1 或 3、p3 = 2 或 4。总是选择最小邻居的粗心实现在这里可能仍然有效，但如果遍历根选择不当并且在写入输出索引时不遵守约束，假设父子结构的基于 DFS 的尝试可能会失败。 

另一种情况是星形树，其中节点 1 连接到所有其他节点。 在这种情况下，所有 pi 值都可以为 1，这是有效的，但假设每个顶点必须选择不同伙伴的实现将会失败。 

## 方法

 一种强力解释是，对于从 1 到 n-1 的每个顶点 i，扫描所有边并找到与 i 相关的边。 这是正确的，因为树中每个顶点至少有一个邻居，因此这样的边总是存在。 然而，扫描每个顶点的所有边的成本为 O(n^2)，因为有 n − 1 个顶点和 n − 1 条边，在最坏的情况下导致大约 10^10 次检查，这是不可能的。 

关键的观察是我们根本不需要搜索。 输入已经隐式地为我们提供了邻接信息。 如果我们构建一个邻接列表，每个顶点都会立即知道它的邻居，因此我们可以在每个顶点的恒定时间内选择任何一个邻居。 这将问题从重复搜索减少到单个预处理步骤加上线性分配过程。 

树的结构保证每个顶点至少有一个相邻顶点，因此邻接表永远不会为空。 这确保我们始终可以选择有效的 pi。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力扫描每个顶点的边缘 | O(n^2) | O(n^2) | O(n) | 太慢了|
 | 建立邻接表并选择任何邻居 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1. 读取所有边并为每个顶点构造邻接表。 这使得每个邻居可以在恒定时间内直接访问任何节点的所有邻居。 
2. 对于从 1 到 n − 1 的每个顶点 i，查看其邻接列表并选择任意邻居。 常见的确定性选择是遇到的第一个邻居。 这确保 pi 始终有效，因为邻接表仅包含由边连接的顶点。 
3.按顺序输出每个i的pi。

主要的设计决策是我们永远不需要考虑顶点 n 的输出，因为问题只要求 n − 1 以内的值。邻接表保证每个这样的顶点至少有一个邻居，因此不需要对叶子或内部节点进行特殊处理。 

### 为什么它有效

 正确性依赖于这样一个不变量：树中每个顶点的度数至少为 1，除了在 n = 1 的情况下，这种情况被 n ≥ 2 排除。由于邻接列表是直接从边构建的，因此保证从中选择的任何邻居都形成有效的边。 由于每个 pi 都是独立选择的，并且仅受局部邻接性约束，因此除了边缘有效性之外，没有全局一致性要求。 因此，为每个节点选择任意邻居总是会产生有效的输出。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    adj = [[] for _ in range(n + 1)]
    
    for _ in range(n - 1):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)
    
    res = []
    for i in range(1, n):
        res.append(str(adj[i][0]))
    
    print(" ".join(res))

if __name__ == "__main__":
    solve()
```该实现以 O(n) 的时间构建标准邻接表。 每条边插入两次，每个端点插入一次，保留无向结构。 

在生成答案时，我们仅按照要求迭代最多 n − 1 次。 对于每个节点，我们访问 adj[i][0]，这是安全的，因为树中的每个节点都有至少一个邻居。 不需要排序或优先级，因为任何有效的邻居都满足条件。 

一个微妙的实现细节是确保索引从 1 开始，与问题陈述相匹配。 另一个是我们从不尝试处理空邻接表，因为树属性保证非空。

 ## 边缘情况

 在二节点树中，邻接表是[2]和[1]。 该算法直接从 adj[1][0] 分配 p1 = 2，产生唯一有效的输出。 

在以 1 为中心的星形中，adj[1] 包含所有其他节点，而所有叶子仅包含 1。对于从 1 到 n − 1 的 i，每个叶子 i 的 adj[i][0] = 1，节点 1 选择其第一个邻居，通常为 2。每个分配仍然是有效边，因为所有边都通过中心连接。 

在深度路径中，每个内部节点恰好有两个邻居。 该算法始终选择第一个插入的邻居，这是由输入顺序确定的，并且仍然保证邻接性。 正确性不依赖于跨节点选择之间的一致性，仅依赖于通过构造保留的局部边缘有效性。
