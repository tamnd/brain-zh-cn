 ## 解决方案
 ## 问题理解

 我们得到了两个平行的岩石类型序列，每个序列都是同一组标签的排列。 玩家只能从左侧和右侧修剪两个序列。 Frodo 从每个序列中删除一个前缀，而 Sam 从每个序列中删除一个后缀。 在这些移除之后，剩余的两个中间部分必须变得完全相同，这意味着它们以相同的顺序代表相同的岩石类型序列。 

一次操作的成本取决于有多少岩石被破坏。 Frodo 为每块从左侧移除的岩石付费，Sam 为每块从右侧移除的岩石付费，单位成本 F 和 S 不同。目标是选择切割位置，以便最终的中间部分匹配并至少保留一块岩石，同时最小化总破坏成本。 

每个有效的解决方案对应于选择 P 中的连续段和 Q 中的相同长度和相同内容的连续段。 一旦选择了这样一对段，这些段之外的所有内容都将被删除。 优化问题变成选择最小化删除成本的最佳匹配片段对。 

约束允许最多 100000 个元素，因此不可能对所有子段进行任何二次比较。 即使 O(N^2) 子串匹配也远远超出了限制。 这立即表明我们必须将问题简化为支持线性或近线性字符串处理的结构，例如后缀数组或结合LCP推理的滚动哈希。 

当考虑正确性时，会出现一个微妙的问题：即使我们找到一个很长的公共段，仅仅最大化它的长度是不够的。 成本还取决于该片段在两种排列中出现的位置。 早期段对于 Frodo 来说更便宜，后期段对于 Sam 来说更便宜，因此相同段长度的两次出现可能会产生不同的成本。 

当稍短的段出现在更便宜的位置时，仅最大化重叠长度的简单方法可能会失败。 

## 方法

 直接的暴力方法将尝试 P 和 Q 中的每一对起始位置，在字符匹配时进行扩展，并计算每次匹配的成本。 这可以正确找到所有公共子数组，但每次比较都可能需要线性时间，导致最坏情况下为 O(N³)，这对于 N 高达 100000 时不可用。 

一个更结构化的观点是认识到问题从根本上来说是寻找两个序列之间的最佳公共子串，其中“最佳”不仅是最长的，而且在位置相关成本函数下也是最便宜的。 

关键的观察是，每个有效解都对应于 P 和 Q 的公共子串，并且每个公共子串都作为 P 中某些后缀和 Q 中某些后缀的前缀出现。因此，我们可以使用后缀，而不是直接枚举子串。 

通过使用分隔符串联 P 和 Q 构建后缀数组，我们可以计算相邻后缀之间的最长公共前缀。 任何公共子串必须显示为某个相邻对的 LCP，其中一个后缀来自 P，另一个来自 Q。这将搜索空间从所有子串对减少到 O(N) 候选对。 

对于每个这样的对，我们使用两个后缀的确切位置及其 LCP 长度来计算最佳成本。 我们评估该候选子串的成本公式并取最小值。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(N3) | O(1) | O(1) | 太慢了 |
 | 后缀数组+LCP| O(N log N) | O(N log N) | O(N) | 已接受 |

 ## 算法演练

1. 将 P 和 Q 连接到单个数组中，并用未出现在任一排列中的唯一分隔符分隔。 这确保了来自不同方面的后缀保持可区分。 
2. 为组合序列构建后缀数组以及 LCP 数组。 这允许我们按排序顺序计算任意两个相邻后缀之间的最长公共前缀。 
3. 迭代后缀数组中的相邻对。 每当一个后缀源自 P 而另一个后缀源自 Q 时，我们就识别出一个候选公共子串。 
4. 令i为P中的起始位置，j为Q中的起始位置。令L为这些后缀之间的LCP值。 这意味着 P[i..i+L-1] 匹配 Q[j..j+L-1]。 
5. 对于每个候选者，计算删除所选段之外的所有内容的总成本。 成本取决于从两个数组的左侧和右侧删除了多少元素。 这变成了基于 i、j 和 L 的直接算术表达式。 
6. 跟踪 L 至少为 1 的所有有效候选者的最小成本，因为最后一段不能为空。 

### 为什么它有效

 每个有效的最终配置对应于 P 和 Q 的公共子串。每个这样的子串都显示为某个后缀对的前缀，并且后缀数组保证至少一个按字典顺序的相邻对捕获该后缀对的最大可能共享前缀。 由于我们评估所有相邻的跨数组对，因此考虑每个最大公共子串，并且较短的子串通过它们在后缀结构中的出现而被隐式覆盖。 成本函数仅取决于所选子串的端点，因此独立评估每个候选可以保留最优性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def build_suffix_array(s):
    n = len(s)
    k = 1
    sa = list(range(n))
    rank = s[:]
    tmp = [0] * n

    def key(i):
        return (rank[i], rank[i + k] if i + k < n else -1)

    while True:
        sa.sort(key=key)
        tmp[sa[0]] = 0
        for i in range(1, n):
            tmp[sa[i]] = tmp[sa[i - 1]] + (key(sa[i - 1]) < key(sa[i]))
        rank = tmp[:]
        if rank[sa[-1]] == n - 1:
            break
        k <<= 1

    return sa, rank

def build_lcp(s, sa, rank):
    n = len(s)
    h = 0
    lcp = [0] * n
    for i in range(n):
        r = rank[i]
        if r == 0:
            continue
        j = sa[r - 1]
        while i + h < n and j + h < n and s[i + h] == s[j + h]:
            h += 1
        lcp[r] = h
        if h:
            h -= 1
    return lcp

def solve():
    n, f, s = map(int, input().split())
    p = list(map(int, input().split()))
    q = list(map(int, input().split()))

    sep = 0
    arr = p + [sep] + q
    n1 = len(p)

    sa, rank = build_suffix_array(arr)
    lcp = build_lcp(arr, sa, rank)

    INF = 10**30
    ans = INF

    total_const = 2 * n * s - 2 * f

    for i in range(1, len(sa)):
        a, b = sa[i - 1], sa[i]
        if (a < n1) == (b < n1):
            continue

        L = lcp[i]
        if L <= 0:
            continue

        if a < n1:
            ip = a
            iq = b - (n1 + 1)
        else:
            ip = b
            iq = a - (n1 + 1)

        L = min(L, n - ip, n - iq)
        if L <= 0:
            continue

        val = (f - s) * (ip + iq) - 2 * s * (L - 1)
        ans = min(ans, val)

    print(ans + total_const)

if __name__ == "__main__":
    solve()
```后缀数组是使用迭代排名加倍构建的，这在实践中足以容纳 200k 元素。 LCP 数组是使用标准 Kasai 方法计算的。 

仅当一个来自 P 另一个来自 Q 时才检查每个相邻后缀对。它们的 LCP 给出了从这些位置开始的最大共享段，我们直接评估成本公式。 最终答案的不断变化导致了所选片段之外的完全删除。 

一个常见的微妙之处是连接数组和原始 Q 位置之间的索引转换，它必须正确减去分隔符和前缀长度。 

## 工作示例

 考虑一个简单的情况，其中 P 和 Q 已经完美匹配。 后缀数组会将相同的后缀放置在相邻的位置，产生等于 N 的大 LCP。该算法选择该完整段，导致段内零删除，仅边界删除，这是最佳的。 

在匹配段出现在不同偏移量的第二种情况下，后缀数组仍然与相应的后缀配对。 LCP 正确捕获重叠长度，并且成本比较确保稍短但较早出现的段可以击败较长但位置昂贵的段。 

| 步骤| SA 配对 | 液晶聚合物| 我（P）| j (Q) | 线段长度| 成本贡献|
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 交叉对| 左 | 我| j | 左 | 计算值|
 | 2 | 下一对 | L'| 我'| j'| L'| 计算值|

 每一行对应于评估一个候选子串。 所有行中的最小值得出最终答案。

 ## 边缘情况

 当最佳匹配子串非常短但出现在非常有利的位置时，就会出现一种边缘情况。 天真的最长公共子串方法会错过它。 基于后缀数组的评估仍然会考虑它，因为它显示为某个相邻后缀对的 LCP。 

另一种边缘情况是 P 和 Q 共享多个相同长度但位置不同的相同子串。 该算法正确区分它们，因为成本取决于 i 和 j，而不仅仅是长度。 

最后的边缘情况是唯一匹配的长度为 1 时。即使在这种最小重叠场景中，算法仍然可以正确评估它，因为考虑了每个 LCP ≥ 1 的跨数组后缀对。
