 ## 解决方案
 ## 问题理解

 该区域是一个矩形网格，其中每个单元格最初都包含一个活跃的地雷。 在此过程中，细胞被一一去除。 查询询问严格位于给定单元的四个方向之一的最近的剩余地雷。 对于垂直查询我们只关心同一列，对于水平查询我们只关心同一行。 

输入描述了网格尺寸和操作序列。 删除操作会永久删除单元格。 搜索操作询问在请求的方向上尚未删除的最近单元的坐标，或者报告不存在这样的单元。 

限制是主要困难。 网格最多可以包含 400 万个单元，并且最多可以有 100 万个操作。 为每个查询扫描整行或整列的成本太高了。 在最坏的情况下，单个查询可以检查 2000 个单元，对所有操作进行大约 20 亿次检查。 该解决方案每次操作都需要几乎恒定的时间。 

删除操作有一个有用的属性：单元格只会消失，不会返回。 这意味着我们可以使用专为单调消除而设计的数据结构。 我们只需要跳过已经被删除的单元格。 

一些边界情况可能会破坏直接实现。 来自网格边缘的查询可能立即没有可能的答案。 例如：```
1 3 3
l 1 1
r 1 3
u 1 2
```输出是：```
-1
-1
-1
```粗心的实现可能会意外地包含起始单元格或在搜索时移出网格。 

另一种情况是最近的单元被移除但更远的单元仍然存在的方向：```
1 4 3
c 1 2
r 1 1
l 1 4
```输出是：```
1 3
1 1
```移除后`(1,2)`，正确的查询必须跳过它并找到`(1,3)`。 在第一个移除的位置停止会给出错误的结果。 

最后一个棘手的情况是多次删除后重复搜索：```
2 2 4
c 1 1
c 1 2
d 1 1
r 2 1
```输出是：```
2 1
2 2
```即使行或列的大部分消失后，该结构也必须继续寻找剩余的单元格。 

## 方法

 一种简单的方法是存储哪些单元格仍然处于活动状态，并且对于每个查询，沿着请求的方向一次走一步，直到找到活动单元格。 这是正确的，因为遇到的第一个活动单元格恰好是最接近的单元格。 问题在于重复工作量。 对于 2000 x 2000 的网格，一个查询可能会扫描 1999 个单元格，而一百万个这样的查询可能需要近 20 亿次操作。 

关键的观察结果是细胞仅被删除。 我们再也不需要埋设地雷了。 对于一行，删除一列后，到达该位置的每个未来查询都应立即跳过它。 这同样适用于每列。 

这正是由不相交集合样式的“下一个指针”结构处理的情况。 对于每一行，我们维护一个可以找到下一个剩余列和上一个剩余列的结构。 对于每一列，我们维护下一个和上一个剩余行。 当删除单元格时，我们将其连接到下一个可用位置，从而有效地将其从未来的搜索中删除。 

例如，如果一行包含列`1 2 3 4`和列`2`被删除，下一个指针`2`变成`3`。 任何未来的搜索开始于`1`要求下一个活动列会自动跳过已删除的单元格。 

这四种结构一起在几乎恒定的摊销时间内回答所有方向。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(q * 最大(n, m)) | O(纳米) | 太慢了 |
 | 最佳 | O(q α(nm)) | O(纳米) | 已接受 |

 ## 算法演练

 1. 构建四个不相交的集合结构。 对于每一行，存储“下一个活动列”结构和“上一个活动列”结构。 对于每一列，存储行的等效两个结构。 每个结构最初都指向自身，因为每个细胞都存在。 
2. 对于移除操作`(x, y)`，从其行结构和列结构中删除该单元格。 在下一个指针结构中，将删除的位置连接到下一个位置。 在前一个指针结构中，将其连接到前一个位置。 
3. 对于正确的查询`(x, y)`，询问行的下一个指针结构之后的第一个活动列`y`。 如果结果超出有效列范围，则不存在答案。 否则，返回`(x, result)`。 
4. 对于左查询，使用行的前一个指针结构。 对于向上查询，请使用列的前一个指针结构。 对于向下查询，请使用列的下一个指针结构。 

这样做的原因是唯一的更改是删除。 删除的位置始终会重定向到仍然可能是有效答案的最接近的位置。 路径压缩使得重复跳转变得非常便宜，因为长链很快就会崩溃。 

### 为什么它有效

 不变的是每个指针结构都返回其方向上最接近的仍然存在的位置。 最初这是正确的，因为每个单元都存在并且每个指针都指向其自身。 当一个单元被删除时，它会被一个到该方向上最近的幸存邻居的链接所取代。 任何将来到达已删除单元格的搜索都会被重定向到删除后应找到的位置。 由于单元格永远不会再次插入，因此任何更新都不会使此属性无效。 

## Python 解决方案```python
import sys
from array import array

input = sys.stdin.readline

def find(arr, idx):
    root = idx
    while arr[root] != root:
        root = arr[root]
    while arr[idx] != idx:
        nxt = arr[idx]
        arr[idx] = root
        idx = nxt
    return root

def solve():
    n, m, q = map(int, input().split())

    row_size = m + 1
    col_size = n + 1

    row_next = array('H', [0]) * (n * row_size)
    row_prev = array('H', [0]) * (n * row_size)
    col_next = array('H', [0]) * (m * col_size)
    col_prev = array('H', [0]) * (m * col_size)

    for i in range(n):
        base = i * row_size
        for j in range(m + 2):
            if j <= m:
                row_next[base + j] = j
            if j <= m:
                row_prev[base + j] = j

    for j in range(m):
        base = j * col_size
        for i in range(n + 1):
            col_next[base + i] = i
            col_prev[base + i] = i

    out = []

    for _ in range(q):
        parts = input().split()
        typ = parts[0]
        x = int(parts[1]) - 1
        y = int(parts[2]) - 1

        if typ == 'c':
            rb = x * row_size
            cb = y * col_size

            row_next[rb + y] = find(row_next, rb + y + 1) - rb
            row_prev[rb + y] = find(row_prev, rb + y - 1) - rb

            col_next[cb + x] = find(col_next, cb + x + 1) - cb
            col_prev[cb + x] = find(col_prev, cb + x - 1) - cb
        elif typ == 'r':
            rb = x * row_size
            ans = find(row_next, rb + y + 1) - rb
            if ans > m - 1:
                out.append("-1")
            else:
                out.append(f"{x + 1} {ans + 1}")
        elif typ == 'l':
            rb = x * row_size
            ans = find(row_prev, rb + y - 1) - rb
            if ans < 0:
                out.append("-1")
            else:
                out.append(f"{x + 1} {ans + 1}")
        elif typ == 'd':
            cb = y * col_size
            ans = find(col_next, cb + x + 1) - cb
            if ans > n - 1:
                out.append("-1")
            else:
                out.append(f"{ans + 1} {y + 1}")
        else:
            cb = y * col_size
            ans = find(col_prev, cb + x - 1) - cb
            if ans < 0:
                out.append("-1")
            else:
                out.append(f"{ans + 1} {y + 1}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```该代码将每个行和列结构存储在扁平数组中。 这避免了数百万个单独的 Python 对象的开销。 由于所有指数最多为 2000，`array('H')`就足够了，因为每个存储的值都适合一个无符号 16 位整数。 

这`find`函数是通常的不相交集合查找和路径压缩。 第一个循环找到最终的生存位置，第二个循环缩短了路径，因此后面的查询速度更快。 

删除顺序很重要。 该代码首先将删除的单元格与其邻居连接起来，然后将来的查询将永远不会再次返回该单元格。 这`+1`和`-1`偏移量也很重要，因为查询要求严格位于给定位置之后或之前的单元格。 

Python中不存在整数溢出问题，并且数组大小由网格尺寸控制。 使用紧凑数组节省内存是必要的，因为超过四百万个单元的四个结构对于普通的 Python 列表来说太大了。

 ## 边缘情况

 第一个边界情况是来自网格边缘的查询。 在输入中：```
1 3 1
l 1 1
```该算法要求提供该列的前一列`0`在从零开始的索引中。 前驱结构返回网格外的哨兵位置，所以答案是`-1`。 

第二种情况是跳过已删除的单元格：```
1 4 2
c 1 2
r 1 1
```删除后`(1,2)`, 列的行后继`1`直接指向列`3`。 查询返回：```
1 3
```无需再次检查移除的电池。 

第三种情况是删除整个行部分：```
2 2 3
c 1 1
c 1 2
d 1 1
```第一行没有剩余单元格，但列结构仍然包含`(2,1)`。 向下查询返回：```
2 1
```因为行和列结构是分开维护的。
