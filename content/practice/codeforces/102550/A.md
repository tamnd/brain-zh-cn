 ## 解决方案
 ## 问题理解

 该地图是一个`n x m`环形网格。 移动到顶部、底部、左侧或右侧边缘之外会环绕到另一侧。 起始房间位于左上角。 有些房间包含带有标记的提示`X`。 

A hint in a room`(i, j)`只有在收集到与起点相比具有较小普通曼哈顿距离的每个提示后才可用。 距离不受包裹运动的影响，只是`i + j`使用基于零的坐标时。 我们需要输出一系列以有效顺序访问所有提示室的动作。 

维度最多为 100，因此最多有 10000 个房间。 从每个房间进行大量图形搜索的解决方案已经接近数亿次操作，并且是不必要的。 重要的限制不是网格的大小，而是所需的首次访问顺序。 我们需要一种自然地跟随曼哈顿距离增加的建筑。 

一个常见的错误是从起始房间运行普通的 DFS。 DFS 可以先深入一个分支，然后再访问距离相同或更小的另一个房间。 例如：```
3 3
S..
X..
..X
```房间`(3,1)`在一个基于索引的情况下有距离`2`， 尽管`(1,2)`有距离`1`。 先下降的DFS可能会尝试输入距离`2`收集距离之前的房间`1`暗示。 

另一个错误是使用暂时增加距离的移动来穿过对角线。 例如，从`(2,2)`到`(3,1)`首先向下进入`(3,2)`，其距离较大，可能仍被锁定。 

该解决方案必须访问距离相等的层中的房间，并且层内的每次移动都必须仅经过当前层或前一层的房间。 

## 方法

 直接的方法是重复搜索下一个可用的提示。 对于每个距离值，我们可以运行 BFS 并找到所有当前可到达的房间。 这是正确的，因为 BFS 尊重未锁定房间的集合，但重复搜索是浪费的。 在最坏的情况下，有 10000 个房间，多次搜索 10000 个房间的图表会比需要的工作量多得多。 

关键的观察结果是每个距离相同的房间都位于一条对角线上。 通过两次移动就可以安全地访问对角线上的连续房间。 如果我们从`(i, j)`到`(i-1, j+1)`，序列`U, R`经过`(i-1, j)`，其距离小一。 相反方向的工作原理与`L, D`。 

这给出了简单的对角线扫描。 我们按升序处理对角线`i + j`。 我们交替每条对角线的方向，使一条对角线的末端紧挨着下一条对角线的起点。 每个房间都被访问一次，并且路径长度保持在限制以下。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O((纳米)^2) | O(纳米) | 太慢了 |
 | 最佳 | O(纳米) | O(纳米) | 已接受 |

 ## 算法演练

 1. 根据距离生成每条对角线`d = i + j`，从`0`并结束于`n + m - 2`。 对角线内的房间坐标都是与该总和成对的。 
2. 完全遍历一条对角线，然后再移动到下一条对角线。 对于偶数对角线，访问从最大行索引到最小行索引的房间。 对于奇数对角线，反转方向。 交替方向使相邻对角线自然连接。 
3. 在对角线内从一个房间移动到下一个房间时，请使用两次移动。 在向下行方向使用`U`然后`R`。 反方向使用`L`然后`D`。 中间房间的距离始终小于正在处理的对角线的距离。 
4. 在两条对角线之间，进行将当前对角线的末端与下一条对角线的起点连接起来的单一移动。 由于顺序交替，这两个房间是相邻的。 

为什么有效：在处理对角线之前`d`，对角线上距离较小的每个房间都已被访问过。 当走过对角线时`d`，唯一的中间房间要么在对角线上`d`或者在较小的对角线上。 在收集所有较小距离提示之前，永远不会输入提示。 完成最后一个对角线后，每个房间都被访问过，因此所有可能的提示都已收集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    ans = []
    current = (0, 0)

    def move_to(a, b):
        nonlocal current
        x, y = current
        nx, ny = a, b

        while x > nx:
            ans.append('U')
            x -= 1
        while y < ny:
            ans.append('R')
            y += 1
        while x < nx:
            ans.append('D')
            x += 1
        while y > ny:
            ans.append('L')
            y -= 1

        current = (x, y)

    for d in range(n + m - 1):
        cells = []
        lo = max(0, d - (m - 1))
        hi = min(n - 1, d)

        if d % 2 == 0:
            for i in range(hi, lo - 1, -1):
                cells.append((i, d - i))
        else:
            for i in range(lo, hi + 1):
                cells.append((i, d - i))

        if cells[0] != current:
            move_to(*cells[0])

        for x, y in cells[1:]:
            cx, cy = current
            if x == cx - 1 and y == cy + 1:
                ans.append('U')
                ans.append('R')
            elif x == cx + 1 and y == cy - 1:
                ans.append('L')
                ans.append('D')
            else:
                move_to(x, y)
            current = (x, y)

        if d + 1 < n + m - 1:
            nd = d + 1
            nlo = max(0, nd - (m - 1))
            nhi = min(n - 1, nd)
            if nd % 2 == 0:
                nxt = (nhi, nd - nhi)
            else:
                nxt = (nlo, nd - nlo)
            if nxt != current:
                move_to(*nxt)

    print(''.join(ans))

if __name__ == "__main__":
    solve()
```该代码不需要检查房间是否包含`X`。 参观空房间是无害的，按照正确的顺序参观每个房间比只参观提示房间更有保障。 

对角线生成使用基于零的坐标，因此单元格的距离恰好是`i + j`。 这`lo`和`hi`值将对角线限制为实际存在于矩形内的单元格。 

对角线单元之间的移动与任意移动分开处理。 特殊的两个字符转换是重要的部分，因为它们保证我们永远不会进入未来的锁定层。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(纳米) | 每个房间都恰好放置在一条对角线上并处理一次。 |
 | 空间| O(纳米) | 输入网格和临时对角线存储最多包含 10000 个房间。 |

 最大路径长度也受到限制。 在对角线内部移动每相邻对使用两次移动，移动次数少于 20000 次。 对角线之间的连接增加了不到 200 次额外移动，安全地保持在所需的 30000 次限制以下。

 ## 边缘情况

 当网格只有一个房间时，起始房间之后没有对角线。 该算法打印一条空路径，这是正确的，因为没有要收集的提示。 

当所有房间都包含提示时，必须访问每个房间。 对角线扫描仍然有效，因为每个新进入的房间都属于当前距离图层或前一个距离图层。 对于空单元格没有捷径假设。 

当一维等于一时，对角线遍历就变成沿着唯一可能的方向直线行走。 转移公式仍然会产生有效的相邻移动，因为对角线最多包含一个单元格。 

当提示出现在相邻对角线上时，交替顺序很重要。 基于行的简单遍历可以在访问更近的提示之前进入更远的行。 对角线顺序可以防止这种情况，因为距离层是主要排序规则。
