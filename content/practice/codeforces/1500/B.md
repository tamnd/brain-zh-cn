 ## 问题理解

 我们有两个循环的颜色序列。 

第一个吊灯重复阵列`a`长度`n`，第二个吊灯重复一个数组`b`长度`m`。 当天`d`，第一个吊灯显示位置`(d - 1) mod n`，而第二个显示位置`(d - 1) mod m`。 

有时，两个枝形吊灯都会显示相同的颜色。 在所有其他日子里，它们显示不同的颜色。 我们要求找出不匹配天数恰好达到的那一天`k`。 

困难在于`k`可以大到`10^12`。 我们无法一天一天地模拟。 

每个序列内的颜色值是不同的。 一种颜色可以在两个序列中出现，但在同一序列中只能出现一次。 这种独特性是问题的关键结构属性。 

长度可以达到`500000`，所以即使是`O(nm)`预处理是不可能的。 解决方案必须保持接近线性或近线性`n + m`。 

一个特别危险的错误是假设该模式每次都会重复`lcm(n,m)`天，然后明确构建一个时期的所有天。 什么时候`n = 499999`和`m = 500000`，最小公倍数大致为`2.5 × 10^11`，太大了，无法一一列举。 

当一种颜色仅存在于一个枝形吊灯中时，会发生另一种微妙的情况。```
n = 2, m = 2
a = [1, 2]
b = [1, 3]
```颜色`2`和颜色`3`永远无法创造一个匹配的日子。 尝试对每个位置进行配对而不检查两个数组中是否存在颜色的解决方案将计算不存在的匹配。 

当两个序列中存在共同颜色但其位置模数不兼容时，会出现第三种边缘情况`gcd(n,m)`。```
n = 4, m = 6
a = [1, 2, 3, 4]
b = [5, 6, 1, 7, 8, 9]
```颜色`1`出现在位置`0`和`2`。 自从`gcd(4,6)=2`、同余式```
x ≡ 0 (mod 4)
x ≡ 2 (mod 6)
```没有解决办法。 这种颜色永远不会产生匹配的日子。 粗心的 CRT 实现可能会错误地计算它。 

## 方法

 蛮力的想法很简单。 对于每一天，计算两个周期中的活跃位置，比较颜色并计算不匹配的数量。 一旦失配计数达到`k`，返回当前日期。 

这是有效的，因为流程的定义是直接的。 不幸的是，答案可能就在附近`10^12`，因此模拟最多需要一万亿次迭代。 

第一个观察结果是，唯一有趣的日子是匹配的日子。 如果我们可以计算出第一个匹配天数中出现了多少天`x`天，然后```
mismatches(x) = x - matches(x).
```答案变成最小的一天`x`这样```
x - matches(x) ≥ k.
```这立即表明二分搜索。 

剩下的问题是有效地计算匹配天数。 

因为每种颜色在每个序列中最多出现一次，所以一种颜色最多可以生成一个同余系统：```
day ≡ position in a (mod n)
day ≡ position in b (mod m)
```对于每种常见颜色，该系统要么没有解决方案，要么产生匹配天数的算术级数。 进展有周期`lcm(n,m)`。 

因此，我们不考虑日子，而是考虑常见的颜色。 对于每种常见颜色，我们使用中国剩余定理确定第一个匹配日。 那么，给定一个极限`x`，我们计算每个级数最多有多少项`x`。 

共有颜色总数最多为`min(n,m)`，这最多是`500000`，使这种预处理变得可行。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O（答案）| O(1) | O(1) | 太慢了 |
 | 最佳| O((n + m) log(max(n,m)) + min(n,m) log(10^2)) | O(n + m) | 已接受 |

g = gcd(n,m).
```存在解当且仅当```
(pa - pb) mod g = 0.
