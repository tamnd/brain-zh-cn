 ## 问题理解

 每个帐户都带有一定数量的“奥术灰尘”，并且有固定的卡组列表，每个卡组都需要特定的灰尘成本才能完全制作。 对于每个帐户，如果我们选择任意套牌子集，我们想知道可以制作的完整套牌的最大数量，但限制是每个所选套牌消耗其全部所需的灰尘，并且所有选定的成本总和必须在帐户的灰尘预算之内。 

更具体地说，我们得到一个数组`A`尺寸的`n`， 在哪里`A[i]`是帐户可用的灰尘`i`。 我们还得到了一个数组`B`尺寸的`m`，其中每个`B[j]`是制作套牌的成本`j`。 对于每个`A[i]`，我们必须选择一个子集`B`最大化所选元素的数量，使其总和不超过`A[i]`。 

限制因素`n, m ≤ 10^5`立即排除任何尝试重新计算每个帐户背包的解决方案。 一种简单的每帐户动态编程方法需要`O(n * m)`时间，其顺序为`10^10`最坏情况下的操作，远远超出1秒的限制。 

一个关键的微妙之处是，我们不要求最大化价值或计算每个帐户的不同组合，只要求项目数量。 这使得排序后的结构变得贪婪。 

一个常见的失败案例来自于没有对甲板成本进行排序。 如果我们先挑选昂贵的牌组，我们就可以人为地减少数量。 例如，如果`A = 10`和`B = [8, 7, 3, 2]`，先选 8 只给出一副牌，而最优的是`[2, 3, 7]`或者`[2, 3]`根据预算，明确显示任意顺序贪婪是不正确的。 

另一个边缘情况是零成本套牌。 如果`B = [0, 0, 5]`和`A = 1`，我们可以先拿两套零成本牌，然后在预算允许的情况下仍然有可能拿 5 成本牌。 任何忽略零或假设严格正性的方法都可能会错误计数。 

## 方法

 蛮力的想法很简单。 对于每个帐户，我们尝试所有套牌子集，计算其总成本，并跟踪适合预算的最大子集大小。 这是正确的，因为它直接强制约束定义，但它需要枚举`2^m`每个帐户的子集，即使对于小帐户也是不可能的`m`。 

更结构化的强力方法是按大小对子集进行排序，或者尝试每个帐户使用背包 DP。 这导致伪多项式解`O(n * m * max(A))`精神上，但仍然不可行，因为`A[i]`可以大到`10^9`。 

关键的观察是，由于每套牌都贡献相同的“价值”（一个精心制作的牌组），因此我们应该始终首先选择更便宜的牌组。 一旦我们排序`B`按照非递减顺序，任何固定预算的最佳策略是采取尽可能多的最小成本，直到超出预算。 这将每个查询变成前缀和问题，然后进行二分搜索。 

我们预先计算排序后的`B`及其前缀和。 然后对于每个`A[i]`，我们找到最大的前缀索引，使得前缀和 ≤`A[i]`。 该索引就是答案。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n·2^m) | O(n·2^m) | O(1) | O(1) | 太慢了|
 | 最优（排序+前缀+二分查找）| O(m log m + n log m) | O(m log m + n log m) | O(米) | 已接受 |

 ## 算法演练

 我们将问题转化为回答多个“预算中有多少个最小元素”的查询。 

1. 对数组进行排序`B`按升序排列。 这确保了我们总是首先考虑更便宜的牌组，这是必要的，因为每副牌对计数的贡献是相等的。 
2.构建前缀和数组`P`， 在哪里`P[k]`代表制作第一个所需的总灰尘`k`最便宜的甲板。 这将子集和转换为单调序列。 
3. 每个账户的预算`A[i]`，执行二分查找`P`找到最大的索引`k`这样`P[k] ≤ A[i]`。 该帐户的答案是`k`。 
4. 按顺序输出所有答案。 

二分查找之所以有效，是因为前缀和数组是严格非递减的，因此可行性（`P[k] ≤ A[i]`) 是单调的`k`。 

### 为什么它有效

 一旦按照成本对牌组进行排序，任何使用更昂贵的牌组而跳过更便宜的牌组的最佳选择都可以通过交换它们来改进，而不会减少所选牌组的数量，而只会降低或保留总成本。 重复此交换参数会强制所有最佳解决方案进入一个结构，其中所选牌组始终是排序列表的前缀。 这使得解空间是一维的并且完全被前缀和捕获。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    A = list(map(int, input().split()))
    m = int(input())
    B = list(map(int, input().split()))

    B.sort()

    P = [0] * (m + 1)
    for i in range(1, m + 1):
        P[i] = P[i - 1] + B[i - 1]

    def upper_bound(x):
        lo, hi = 0, m
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if P[mid] <= x:
                lo = mid
            else:
                hi = mid - 1
        return lo

    res = []
    for a in A:
        res.append(str(upper_bound(a)))

    print(" ".join(res))

if __name__ == "__main__":
    main()
```排序步骤确保我们总是首先消耗最便宜的牌组。 前缀数组将重复的求和检查转换为单个单调结构。 二分查找有效地找到最大可行前缀长度。 

一个微妙的细节是使用上限样式二分搜索而不是`bisect_right`直接，但两者是等效的。 重要的条件是我们搜索前缀和，而不是原始值。 

零成本牌组很自然地被处理，因为它们对前缀总和的贡献为零，允许前缀索引在不消耗预算的情况下增加。

 ## 边缘情况

 当所有牌组成本为零时，所有前缀的前缀总和保持为零。 算法返回`m`对于每个帐户，因为每个前缀都是可行的。 对于像这样的输入`A = [0, 100]`和`B = [0, 0, 0]`，二分查找总是返回 3，这与无论预算如何都可以使用所有牌的事实相匹配。 

当所有套牌都太贵时，例如`B = [5, 6, 7]`和`A = [0, 4]`，前缀总和从 0 开始，然后立即超出预算。 该算法正确地为所有帐户返回 0，因为即使是最便宜的牌组也买不起。 

当预算非常大时，二分查找总是返回`m`，因为完整的前缀和适合。 这避免了每个查询的任何溢出或迭代累积，并说明了为什么要进行预处理
