 ## 解决方案
 ## 问题理解

 我们得到了一系列宝石，每个宝石都有一个整数级别。 唯一允许的操作是获取至少两个相同级别的连续块并将其合并为一个级别增加一级的宝石。 这个过程可以在序列中的任何地方重复，并且合并可以为进一步合并创造新的机会。 

问题是，在经过一系列此类合并之后，是否有可能将整个数组简化为单个宝石。 

关键的困难在于合并是局部的并且依赖于邻接性，但是它们的影响在值上向上传播。 合并会删除多个元素并用更高级别的元素替换它们，如果相邻出现足够多的相同副本，则该元素可以参与将来的合并。 

约束很大：每个测试用例最多 10^5 个元素，所有测试总共最多 5 × 10^5 个元素。 这立即排除了任何以简单方式重复扫描和合并数组的模拟。 每个测试用例的 n 为二次方的任何方法都会失败。 

当合并创建更高级别的宝石时，会出现一种微妙的边缘情况，这些宝石只有在远处的片段崩溃后才能合并。 例如，即使不同的合并顺序成功，贪婪的从左到右合并也可能会失败。 

另一种边缘情况是当序列几乎一致但被单个不同元素分隔时。 例如，像 [1, 1, 2, 1, 1] 这样的序列可能看起来是可简化的，因为有很多 1，但是 2 会阻止交互，从而阻止形成单个合并链。 

## 方法

 暴力方法将明确模拟合并过程。 人们可以重复扫描数组，找到长度至少为 2 的相同值的任何最大段，将其替换为值 +1 的单个元素，然后重复，直到无法移动为止。 每次扫描的时间复杂度为 O(n)，在最坏的情况下，我们可能执行 O(n) 合并，从而导致每个测试用例的时间复杂度为 O(n^2)。 对于 10^5 个元素，这太慢了。 

关键的观察结果是，该过程仅依赖于连续的运行，并且合并总是会减少运行，同时增加其级别。 我们可以将数组压缩为相等值的运行，而不是跟踪单个元素。 每次运行都由一对（值、计数）来表征。 操作变为：如果一个运行的计数≥2，则可以通过将两个或多个副本替换为一个更高级别的项目来减少该运行，然后该项目可以与同一新级别的相邻运行合并。 

这表明类似于间隔折叠的基于堆栈的减少。 我们从左到右处理运行，维护一个尝试立即解决任何合并机会的结构。 每当两个相邻的组在合并后变得相等时，它们就会进一步合并。 这本质上是对按值索引的计数序列的级联进位过程。 

我们不是模拟元素，而是维护每个值的计数映射或数组，并向上传播“进位合并”。 每次我们积累至少两项相同价值的物品时，它们就会折叠成一件价值+1的物品。 

这类似于二进制加法，只不过基数是 2，但“数字”对应于级别，并且值向上传播。 

最后一个问题归结为在所有进位传播后，所有质量是否可以在某种程度上减少为单个项目。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力模拟| O(n^2) | O(n^2) | O(n) | 太慢了|
 | 运行压缩+进位传播| O(n) | O(n) | 已接受 |

 ## 算法演练

1. 将输入序列压缩为相等值的连续运行，仅存储它们的计数。 这消除了相同块内不相关的内部结构。 
2. 创建一个字典（或数组），将每个值映射到该级别当前可用的“项目”数量。 使用运行计数对其进行初始化：每次运行贡献其值的一项，但如果运行长度至少为二，则它立即贡献一个更高级别的合并项目，而不是多个单个项目。 
3. 按升序处理值，保持类似进位的传播。 在每个级别 v，获取当前可用的项目数。 
4. 当级别 v 的计数至少为 2 时，重复将对合并到级别 v + 1。每次合并将 v 的计数减少 2，并将 v + 1 的计数增加 1。这种情况会一直持续，直到 v 中剩余的项目少于两个。 
5. 向上移动到下一个级别并重复相同的过程，包括从先前的携带中新创建的项目。 
6. 处理完结构中出现的所有级别（包括由进位创建的级别）后，检查是否存在单个剩余项。 如果总体上仅保留一项，则答案为“是”，否则为“否”。 

关键思想是合并仅取决于每个级别的计数的类似奇偶校验的行为。 某个级别上的任何偶数计数都会完全向上传播，而奇数计数会留下无法消除的余数，除非更高级别上存在进一步的结构。 

### 为什么它有效

 在任何级别 v，只能合并相同的项目对，并且每次合并都会严格增加级别。 由于没有任何操作会降低级别，因此级别之间的交互是单向向上流动的。 这意味着系统的行为就像一个多级进位过程，其中每个级别独立地分解为零个或一个剩余项目，并进位到下一个级别。 由于进位是确定性的并且与顺序无关，因此最终的配置是唯一的。 如果在完全传播后仅剩下一件物品，则相当于结构完全塌陷为单个宝石。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    from collections import Counter
    
    cnt = Counter()
    for x in a:
        cnt[x] += 1
    
    # we may need to propagate upward dynamically
    keys = sorted(cnt.keys())
    max_key = max(keys) if keys else 0
    
    # use dict for dynamic levels
    while True:
        changed = False
        new_cnt = Counter()
        
        for v in sorted(cnt.keys()):
            c = cnt[v]
            if c >= 2:
                carry = c // 2
                rem = c % 2
                if rem:
                    new_cnt[v] += rem
                new_cnt[v + 1] += carry
                changed = True
            else:
                new_cnt[v] += c
        
        cnt = new_cnt
        
        if not changed:
            break
    
    total = sum(cnt.values())
    print("Yes" if total == 1 else "No")

if __name__ == "__main__":
    solve()

t = int(input())
for _ in range(t):
    solve()
```该实现维护了各个级别的频率图。 每次迭代都会执行一轮完整的向上传播，从而折叠所有可用的对。 循环继续，直到没有级别至少有两个项目，这意味着不可能进一步合并。 

关键的实现选择是使用计数器而不是模拟序列。 这避免了对邻接的依赖，因为在压缩和抽象之后，邻接仅在形成初始相同组时起作用。 

一个微妙的问题是终止：当没有级别的计数≥2时，系统稳定，因为不存在进一步的合并。 那时，所有剩余的项目都是孤立的，因为它们无法进一步组合。

 ## 边缘情况

 像 [k] 这样的单元素数组已经是一个完成的配置。 该算法用一项初始化计数器，并立即发现不可能进行合并。 由于总计数为 1，因此它正确输出 Yes。 

像 [1, 2] 这样严格交替的小配置根本不会产生合并。 每个值在其自己的级别上保持隔离，因此最终计数为 2，答案为“否”。传播循环不会改变任何内容，因为没有级别的计数 ≥ 2。 

像 [1, 1, 1, 1, 1, 1] 这样的完全均匀的数组展示了最大级联。 在第 1 级，三轮配对会产生更高级别的进位，直到只剩下一个最终项目。 该算法重复进行整数除以二，确保向上传播的正确性。
