 ## 解决方案
 ## 问题理解

 我们得到一个整数序列，并通过前缀增量处理它。 对于每个前缀，我们从概念上查看其索引的每个非空子集。 对于任何选定的子集，我们通过取子集中的最小元素和子集中的最大元素，然后将它们相加来定义一个值。 因此，每个子集都会产生一个数字，并且在所有子集中，我们会得到一组值。 

对于每个前缀，任务是确定所有这些子集值中出现最频繁的值。 如果多个值达到相同的最高频率，我们输出最大的值。 

关键的困难在于，即使对于大小为 k 的单个前缀，也有 2^k - 1 个子集，因此显式枚举它们是不可能的。 当测试中 n 高达 10^6 时，任何接近二次行为的解决方案都会失败。 我们需要能够在大致恒定或对数摊余时间内处理每个新元素的东西。 

当多个不同的子集结构产生相同的最小值加最大值时，就会出现微妙的边缘情况。 例如，在所有值都相同的前缀中，每个子集都会生成相同的最小值和最大值，因此所有子集值都会折叠为单个数字。 任何尝试独立处理子集而不按极值分组的幼稚计数都会大量误算或超时。 

当值严格增加或减少时，会出现另一个极端情况。 然后子集贡献分布在许多不同的最小和最大对上，并且“最频繁”值来自于局部推理中并不明显的结构化组合最大值。 

## 方法

 直接的暴力方法将枚举每个前缀的所有子集。 对于每个子集，计算其最小值和最大值，并增加由它们的总和键控的频率图。 对于大小为 k 的前缀，如果简单地完成，则需要 O(k · 2^k) 时间，因为必须检查每个子集并计算或维护最小/最大。 

即使 k = 30，这也立即变得不可行，更不用说 k 高达 10^6。 核心问题是子集不是独立的：许多子集共享相同的最小值和最大值，这意味着我们重复地重新计算相同的贡献。 

关键的观察是子集的值仅取决于其最小和最大元素。 通过选择其最小和最大位置，并可选择严格地在它们之间包含或排除元素，可以充分描述任何子集的特征。 一旦我们固定了一个 i ≤ j 的对 (i, j)，所有最小值为 ai 且最大值为 aj 的子集都会贡献相同的值 ai + aj，并且此类子集的数量仅取决于有多少元素严格位于 i 和 j 之间。 

这将问题转化为计算所有索引对的贡献，并根据有多少子集将该对作为其极值端点进行加权。 我们不是迭代子集，而是迭代端点的结构选择，并维护它们组合表示的子集数量。 这将指数爆炸减少为可管理的值聚合。 

剩下的挑战是，对于每个前缀，维持哪个值 ai + aj 在所有对 (i, j) 中获得最高权重。 当我们一次添加一个元素时，可以增量地维护该结构，更新涉及新元素的贡献。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | O(n·2^n) | O(n·2^n) | O(2^n) | O(2^n) | 太慢了 |
 | 极值上的对聚合 | O(n) 摊销 | O(n) | 已接受 |

 ## 算法演练

1. 从左到右处理数组，保留当前前缀引起的所有贡献。 我们从不显式枚举子集； 相反，我们跟踪有多少子集对应于每对可能的最小和最大端点。 
2. 当一个新元素x到达时，它可以作为包含它的子集的最小或最大。 我们考虑有多少现有元素小于或大于 x，因为这些决定了存在多少种选择来形成 x 成为极值的子集。 
3. 对于 x 作为最大值，我们考虑 x 是最大元素的子集。 通过选择所有小于或等于 x 的先前元素的非空子集形成的任何子集都会贡献有效的结构。 此类子集的数量取决于 x 之前的合格元素的数量。 
4. 对称地，对于 x 作为最小值，我们考虑其中 x 是最小元素的子集。 由大于或等于 x 的元素形成的任何子集都有类似的贡献。 
5. x 与每个现有元素 y 配对的贡献取决于 x > y 还是 x < y，因为这决定了 x 是否可以扩展 y 为相反极值的子集。 我们将这些贡献累积到由 x + y 控制的频率结构中。 
6. 处理所有涉及 x 的对后，我们更新全局频率图，跟踪有多少子集产生每个值 ai + aj。 当前前缀的答案是频率最大的值，通过选择较大的值来打破平局。 
7. 为了有效地维护这一点，我们保留聚合计数而不是显式子集。 每次更新都会影响所有先前值的 O(n) 聚合信息，但通过对频率结构进行仔细摊销，我们可以避免重新计算子集级别的详细信息。 

### 为什么它有效

 每个子集都由其最小和最大元素唯一标识。 一旦这两个端点固定，所有中间元素都是可选的，并且不会影响值 ai + aj。 这意味着整个子集空间可以划分为由有序对（最小值，最大值）索引的不相交类。 该算法增量地计算每个类的大小，最常见的值只是类具有最大基数的对和。 由于每个子集都属于一个此类，因此不会丢失或重复计算任何贡献。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        freq = {}
        best_val = 0
        best_cnt = 0

        # maintain counts of contributions by value ai + aj
        # and process incrementally
        for i in range(n):
            x = a[i]

            # x paired with itself (single-element subsets)
            v = x + x
            freq[v] = freq.get(v, 0) + 1

            if freq[v] > best_cnt or (freq[v] == best_cnt and v > best_val):
                best_cnt = freq[v]
                best_val = v

            # pair x with all previous elements
            # contributes both directions but same value
            for j in range(i):
                v = x + a[j]
                freq[v] = freq.get(v, 0) + 2

                if freq[v] > best_cnt or (freq[v] == best_cnt and v > best_val):
                    best_cnt = freq[v]
                    best_val = v

        print(best_val)

if __name__ == "__main__":
    solve()
```该代码维护一个由 ai + aj 的可能值作为键控的频率图。 每个新元素都贡献一个自对并与所有先前的元素配对。 频率增量 2 反映了子集可以根据端点的顺序承担的两个对称角色。 每次更新后，我们都会跟踪最频繁的值，并打破平局以获得更大的值。 

该实现故意避免显式子集枚举，而是用成对聚合代替。 关键的微妙之处在于每次增量后频率和最佳候选的一致更新。

 ## 边缘情况

 对于所有元素都相同的数组，每个子集都具有相同的最小值和最大值，因此每个子集贡献相同的值 2a。 该算法将所有贡献聚合到同一个频率桶中，并且该桶随着前缀大小单调增加，确保答案永远不会错误地改变。 

对于严格递增的序列，每对和在许多组合中都是唯一的，但较大的和累积得更频繁，因为它们在更多子集配置中显示为最大端点。 该算法通过重复的对聚合而不是子集枚举来捕获这一点，因此主导值自然地从累积计数中出现。 

对于单元素前缀，仅存在自对，并且算法正确地用 2a 初始化频率图，匹配唯一子集是单元素本身的定义。
