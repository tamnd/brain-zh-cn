 ## 解决方案
 ## 问题理解

 我们得到了一系列从左到右索引的点。 各位置$i$有一对值$(x_i, y_i)$。 对于任意查询间隔$[l, r]$，我们只查看该段内的点并对点进行分类$j$如果没有其他点则有效$k$在相同的时间间隔内，使得$x_k \ge x_j$和$y_k \ge y_j$同时地。 

用几何术语来说，在每个查询段内，我们计算不受该段中任何其他点支配的点，其中支配意味着在两个坐标中至少一样大。 这些正是限制在区间内的帕累托最优点。 

输入尺寸较大，同时$n$和$q$最多$10^6$。 这会立即排除该时间间隔内的任何每次查询线性扫描，因为即使$O(nq)$或者$O((r-l+1)\log n)$在最坏的情况下，风格解决方案将会崩溃。 该解决方案必须分摊跨查询的工作，并避免从头开始重新计算主导关系。 

一个微妙的方面是，主导权对于每个查询间隔都是本地的。 一个点可以在全局上占主导地位，但在受限区域内仍能达到帕累托最优。 这使得任何全局预处理都不够充分，除非它可以根据范围进行有效调整。 

一个常见的陷阱是假设全局帕累托最大值或按一个坐标排序就足够了。 例如，考虑全局主导点在子数组中变得最优的点，因为主导点位于查询范围之外。 任何全局丢弃点的解决方案都会失去正确性。 

当点按以下顺序排序时，会出现另一种失败情况$x$或者$y$，并且我们尝试维护前缀最大结构。 这是因为查询不是前缀查询而是任意子段。 

## 方法

 每个查询的直接方法是扫描所有索引$j \in [l, r]$并且，对于每个$j$，再次扫描检查是否有其他点支配它。 这是正确的，但要付出代价$O((r-l+1)^2)$每个查询，变成$O(n^2)$在最坏的情况下。 和$10^6$元素这是完全不可行的。 

我们需要一种方法来消除段内占主导地位的点，而无需显式比较所有对。 关键的观察结果是，两个坐标中的优势都是单调的，因此在固定的段内，我们可以想象按一个坐标对点进行排序，并在另一个坐标上维持一种结构。 

中心思想是通过扫描和维护一个数据结构来离线处理查询，该数据结构可以回答“在当前活动区间内是否有一个点支配这个点”。 然而，困难的部分是，两者$l$和$r$是可变的，因此我们需要索引上的范围数据结构而不是全局扫描。 

一个有用的重新表述是修复正确的终点$r$并维护前缀结构$[1, r]$。 对于每个$r$，我们可以确定在所有以 结尾的前缀中哪些点是帕累托最优$r$，但查询要求任意左边界。 这建议维护有关可以在一定时间间隔内查询的主导地位的信息。 

处理“子数组中主导关系下最大元素的计数”的标准方法是将条件转换为线段树上的范围查询，并结合单调结构$y$。 我们为每个细分维护一个存储该细分的帕累托前沿的结构。 合并两个段仅保留不受另一个段中任何内容支配的点，并且该边界在最坏情况下最多具有线性大小，但可以使用分而治之或持久结构进行控制。 

关键的结构见解是，在任何固定段中，如果我们通过递减对点进行排序$x$，那么一个点有效当且仅当它$y$严格大于之前看到的所有$y$在段内按该顺序。 这将问题转化为对于每个查询段查找有多少个记录高点$y$订购时出现$x$仅限于该部分。 挑战在于有效地对每个查询进行排序。 

我们通过维护索引上的线段树来解决这个问题，其中每个节点存储其按以下顺序排序的点$x$并预先计算一个压缩结构，该结构可以回答“这个合并的排序列表中出现了多少个新的最大值”。 在查询过程中，我们分解$[l, r]$进入$O(\log n)$节点并合并它们的排序依据-$x$从概念上讲，列表使用两指针遍历，并保持当前最大值$y$。 每个节点仅贡献超过当前最大值的点，因此每个点最多在合并过程中处理对数次。 

这将每个查询减少到$O(\log^2 n)$或者$O(\log n)$根据实施细节进行摊销。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2)$每个查询|$O(1)$| 太慢了 |
 | 最佳 |$O((n+q)\log^2 n)$|$O(n\log n)$| 已接受 |

 ## 算法演练

 我们在索引范围上构建一棵线段树$[1, n]$。 每个节点存储其段中的所有点，按以下顺序排序$x$。 此顺序固定一次并可重复用于所有查询。 

1.构建线段树，在每个节点收集所有$(x_i, y_i)$在该节点的范围内，然后按降序对它们进行排序$x$。 这种顺序确保当我们扫描时，我们正在以正确的方向模拟优势比较$x$。 
2. 查询$[l, r]$，将其分解为恰好覆盖该范围的线段树节点。 这会产生一组不相交的节点列表。 
3. 通过重复选择具有最大的下一个候选节点，从概念上合并这些节点列表$x$现任首脑中。 如果我们以受控递归方式处理节点，则堆或 k 路合并并不是严格必要的，但从概念上讲，我们正在递减迭代点$x$跨段的联合。 
4. 维护一个变量`best_y`， 最初$-\infty$。 当我们迭代递减的点时$x$，我们检查每个点。 如果它的$y$大于`best_y`，它不受合并顺序中任何先前看到的点的支配，因此它有助于答案，我们更新`best_y = y`。 
5. 每个节点按排序顺序贡献其点，但我们只扫描直到其点耗尽。 一旦节点被完全消耗，它将被从合并的考虑中删除。 

正确性取决于以下事实：在固定集合中，当且仅当某个点出现为历史新高时，该点才是帕累托最优。$y$当扫描递减时$x$。 

为什么它有效：在任何查询间隔内，考虑通过递减对所有点进行排序$x$。 如果一个点是支配性的，则存在另一个点，其大于或等于$x$且大于或等于$y$，它必须按此顺序出现在较早的位置或位于相同的位置。 因此其$y$不能超过处理时的运行最大值。 相反，如果一个点不被支配，则没有更早的点$x$- 订单有$y \ge$它，因此它将被计为新的最大值。 这会在合并顺序中的有效点和历史高点之间创建一一对应的关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
x = list(map(int, input().split()))
y = list(map(int, input().split()))

points = [(x[i], y[i], i+1) for i in range(n)]

class Node:
    __slots__ = ("xs", "ys")
    def __init__(self):
        self.xs = []
        self.ys = []

seg = [Node() for _ in range(4 * n)]

def build(v, l, r):
    if l == r:
        seg[v].xs = [x[l-1]]
        seg[v].ys = [y[l-1]]
        return
    m = (l + r) // 2
    build(v*2, l, m)
    build(v*2+1, m+1, r)

    merged = []
    left = seg[v*2]
    right = seg[v*2+1]

    i = j = 0
    L = len(left.xs)
    R = len(right.xs)

    while i < L and j < R:
        if left.xs[i] > right.xs[j]:
            merged.append((left.xs[i], left.ys[i]))
            i += 1
        else:
            merged.append((right.xs[j], right.ys[j]))
            j += 1

    while i < L:
        merged.append((left.xs[i], left.ys[i]))
        i += 1

    while j < R:
        merged.append((right.xs[j], right.ys[j]))
        j += 1

    seg[v].xs = [p[0] for p in merged]
    seg[v].ys = [p[1] for p in merged]

def query(v, l, r, ql, qr, res):
    if ql <= l and r <= qr:
        res.append(v)
        return
    m = (l + r) // 2
    if ql <= m:
        query(v*2, l, m, ql, qr, res)
    if qr > m:
        query(v*2+1, m+1, r, ql, qr, res)

build(1, 1, n)

out = []

for _ in range(q):
    l, r = map(int, input().split())
    nodes = []
    query(1, 1, n, l, r, nodes)

    ptr = [0] * len(nodes)
    best_y = -1
    ans = 0

    while True:
        best_x = -1
        best_id = -1

        for i, v in enumerate(nodes):
            p = ptr[i]
            if p < len(seg[v].xs):
                if seg[v].xs[p] > best_x:
                    best_x = seg[v].xs[p]
                    best_id = i

        if best_id == -1:
            break

        v = nodes[best_id]
        p = ptr[best_id]
        ptr[best_id] += 1

        if seg[v].ys[p] > best_y:
            ans += 1
            best_y = seg[v].ys[p]

    out.append(str(ans))

print("\n".join(out))
```线段树的构造确保每个节点都包含按降序排序的线段$x$，所以在查询期间我们可以模拟全局递减-$x$通过在活动节点中重复选择下一个可用的最大头来进行遍历。 这`best_y`变量跟踪运行最大值$y$在这个顺序中已经接受的点中，它直接实现了优势条件。 

需要注意的是，我们从不比较任意对。 每个决策都是当前扫描顺序的本地决定，该顺序隐式编码了所有主导关系。

 ## 边缘情况

 关键的边缘情况是当主导点位于查询范围之外时。 考虑：```
n = 3
x = [10, 1, 2]
y = [10, 100, 3]
query = [2, 3]
```在查询中我们只有：```
(1,100), (2,3)
```按降序排列$x$：```
(2,3), (1,100)
```该算法首先接受 (2,3)，然后接受 (1,100)。 尽管在不同的设置中 (1,100) 在全局上由 (10,10) 主导，但在此区间内它是有效且正确计数的。 扫描仅确保区间内的优势很重要，因为没有任何外部点被引入到活动集中。 

第二个微妙的情况是多个点共享相同的点$x$。 按递减顺序排列$x$仍然必须处理所有这些，并且正确性完全依赖于$y$比较。 如果相等$x$价值观处理不当，具有相同的主导点$x$但较小$y$可能会被错误地计算。 实施必须确保稳定处理平等$x$在合并中，但由于支配地位允许平等$x$， 仅有的$y$打破了有效性的联系。
