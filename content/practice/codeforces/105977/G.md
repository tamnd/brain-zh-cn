 ## 解决方案
 ## 问题理解

 该问题给出了一系列股票价格$n$天，但价格以对数形式编码。 当天$i$，实际价格为$e^{a_i}$， 在哪里$a_i$是一个正整数。 这将真实市场中的乘法收益和损失转化为指数空间中的加法差异。 

每个查询描述一个时间间隔$[s, t]$。 当天$s$，我们收到一笔贷款$e^k$货币单位。 我们可以在几天内自由交易股票$s$通过$t$，购买零碎股份并进行无限交易。 在一天结束时$t$，所有持股均被清算并偿还贷款。 我们希望还款后的最终财富尽可能最大，再次以指数形式表示$e^w$，任务是输出$w$。 

所以每个查询的核心任务是：从现金开始$e^k$，按已知价格序列最大化套利交易后的最终金额，然后输出所得指数。 

关键的转变是，由于一切都是指数的，因此在对数空间中工作会将乘法增益转变为加法增益。 交易日起$i$今天$j$给出增益因子$e^{a_j - a_i}$，所以在指数空间中它贡献$a_j - a_i$。 

约束条件很大：最多$10^5$天和$10^5$查询。 这立即排除了任何在线性时间内独立重新计算每个查询的最佳交易的解决方案，因为这会导致$10^{10}$运营。 

一种简单的方法是独立处理每个查询并在内部模拟最佳交易$[s, t]$。 然而，即使找到一个时间间隔的最佳策略，如果仔细完成，也需要多次扫描该段，并且对所有查询都这样做是不可行的。 

一种更微妙的失败模式来自于认为答案仅取决于区间内的最低和最高价格。 这是不正确的，因为多次交替增加很重要：最佳策略不一定是一次买入和一次卖出，而是一系列有利可图的举措。 

## 方法

 第一步是了解“无限交易和分数份额的最佳交易”在日志空间中意味着什么。 假设我们在当天购买$i$并在当天出售$j > i$。 增益的指数为$a_j - a_i$。 如果我们执行多项交易，假设我们分成几部分$i_1 < i_2 < \dots < i_k$，总增益变为$$(a_{i_2} - a_{i_1}) + (a_{i_3} - a_{i_2}) + \dots + (a_{i_k} - a_{i_{k-1}}),$$哪些望远镜可以$a_{i_k} - a_{i_1}$如果我们强制严格交替买入/卖出。 但真正的限制是我们并不被迫严格交替； 只有当跨越选定的界限从较低价格转向较高价格时，我们才能获利。 

当我们将交易解释为累积连续增长部分之间的所有正向上差异时，经典的简化就出现了。 如果序列上升，我们捕获该增长； 如果它下跌，我们忽略它并等待更好的切入点。 这会降低最佳增益$[s, t]$所有正相邻差值的总和：$$\sum_{i=s}^{t-1} \max(0, a_{i+1} - a_i).$$那么最终的答案很简单：$$w = k + \sum_{i=s}^{t-1} \max(0, a_{i+1} - a_i).$$蛮力方法独立评估每个查询的总和，扫描间隔。 那是$O(n)$每个查询，变成$O(nm)$总共并不能通过。 

关键的观察是表达式仅取决于相邻差异。 定义$d_i = \max(0, a_{i+1} - a_i)$。 然后每个查询减少为数组上的范围和查询$d$。 通过前缀和，我们可以在预处理后在恒定时间内回答每个查询。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |$O(nm)$|$O(1)$| 太慢了 |
 | 差异前缀和|$O(n + m)$|$O(n)$| 已接受 |

 ## 算法演练

 我们将价格序列转换为差异贡献数组，然后对其进行范围查询。 

1.构造辅助数组$d$长度$n-1$，其中每个元素是$d_i = \max(0, a_{i+1} - a_i)$。 这仅隔离有利可图的向上移动并放弃向下移动，因为在最佳交易下损失不会产生影响。 
2.构建前缀和数组$p$， 在哪里$p[i]$存储总和$d_1$通过$d_i$。 这使我们能够在恒定时间内计算任何间隔总和。 
3. 对于每个查询$[s, t]$，计算区间内的总增益为$p[t-1] - p[s-1]$，因为只有完全在区间内的转换才重要。 
4. 添加底指数$k$达到这个增益，产生最终的指数$w$。 
5、输出$w$。 

差异数组足够的原因是，每个有利可图的交易策略都可以重新排列，以便所有收益完全对应于向上的步骤，而不改变最终结果。 任何交易序列都会分解为收集局部增量。 

### 为什么它有效

 不变的是，在该区间的任何一点，最好的策略都会维持我们要么持有现金，要么持有在最近的局部最低点购买的股票的属性。 每次序列增加时，都可以完全捕获该增加，而不会影响未来的决策。 每一次下跌都会被忽略，因为与等待更低的价格相比，进入那里并不能改善任何后来的退出。 

这将所有最优策略减少为局部单调段的独立贡献，使得正相邻差异的总和既必要又充分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = list(map(int, input().split()))
k = int(input())

n = len(a)
d = [0] * (n - 1)

for i in range(n - 1):
    if a[i + 1] > a[i]:
        d[i] = a[i + 1] - a[i]

prefix = [0] * (n)
for i in range(n - 1):
    prefix[i + 1] = prefix[i] + d[i]

out = []
for _ in range(m):
    s, t = map(int, input().split())
    gain = prefix[t - 1] - prefix[s - 1]
    out.append(str(k + gain))

print("\n".join(out))
```该代码首先通过扫描一次相邻差异来构建增益数组。 前缀数组移动一个索引，以便范围查询与 1 索引输入完全对齐。 

每个查询直接转换为前缀差异。 添加的$k$在查询时完成，以避免在预处理期间重复算术。 

一个常见的陷阱是差一索引：增益数组有大小$n-1$，但查询是指天数。 映射是交易机会存在于日之间$i$和$i+1$，所以查询$[s, t]$涵盖指数$[s, t-1]$在差异数组中。 

## 工作示例

 考虑声明中描述的示例行为。 

对于第一个间隔$[2, 4]$有价格$[2, 4, 5]$，差异是$+2, +1$。 前缀和给出累积增益$3$。 开始于$k = 2$，最终指数变为$5$。 

| 步骤| 间隔 | 差和| 前缀结果 | 最后w |
 | --- | --- | --- | --- | --- |
 | 1 | [2,4]| 2 + 1 = 3 | 3 | 5 |

 这表明多次连续上涨是累积的，而不是被视为单次买卖操作。 

对于第二个间隔$[3, 6]$有价格$[4, 5, 3, 6]$，差异是$+1, 0, +3$, 总结为$4$。 添加碱基$k=2$产量$6$。 

| 步骤| 间隔 | 差和| 前缀结果 | 最后w |
 | --- | --- | --- | --- | --- |
 | 1 | [3,6]| 1 + 0 + 3 = 4 | 4 | 6 |

 这表明该算法正确地跳过向下转换并仅累积有利可图的段。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    k = int(input())

    n = len(a)
    d = [0] * (n - 1)
    for i in range(n - 1):
        if a[i + 1] > a[i]:
            d[i] = a[i + 1] - a[i]

    prefix = [0] * (n)
    for i in range(n - 1):
        prefix[i + 1] = prefix[i] + d[i]

    out = []
    for _ in range(m):
        s, t = map(int, input().split())
        out.append(str(k + prefix[t - 1] - prefix[s - 1]))

    return "\n".join(out)

# minimal size

 ## 边缘情况

 一个微妙的情况是当间隔在上升段内开始或结束时。 例如，在类似的序列中$1, 5, 10, 2, 3$, 一个查询$[2, 4]$只包括$5, 10, 2$。 该算法计算差异贡献$+5$在区间内并忽略从$10$到$2$，因为它没有盈利。 前缀减法正确地仅隔离了内部边界$5 \to 10$。 

另一种情况是单日查询$[i, i]$。 没有转换，因此差值和为零，答案正是$k$。 前缀公式自然会产生零，因为$p[i-1] - p[i-1] = 0$，小心实施时可以防止任何意外的越界或负面索引影响。
