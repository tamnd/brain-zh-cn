 ## 问题理解

 该问题给出了一个固定的历史表，描述了福建省编程竞赛系列赛的 11 个版本。 每个版本都有一个组织大学，并且每个大学都与一个简短的英文缩写相关联。 输入是单个整数`n`，代表我们感兴趣的比赛版本。任务是输出组织比赛的大学的缩写`n`- 第 1 版。 

尽管该语句包含大量噪音和乱码，但实际结构很简单：有一个包含 11 项的静态列表，答案是通过索引直接查找。 

约束条件`1 ≤ n ≤ 11`非常小，这立即排除了任何预处理、搜索或算法优化的需要。 任何执行恒定时间数组索引操作的解决方案就足够了。 

不存在涉及大输入大小或多个查询的隐藏边缘情况。 粗心的实现可能遇到的唯一微妙问题是离一索引，因为像这样的竞赛问题通常从 1 开始编号版本，而编程语言从 0 开始索引数组。 

例如，如果有人错误地将第一版视为索引 0，则输入`1`会错误地映射到第二所大学而不是第一所大学，从而产生错误的缩写，即使逻辑看起来是正确的。 

## 方法

 问题的结构本质上是从整数到字符串的静态映射。 强力解释是通过解析完整的大学表并每次提取缩写来动态重建映射，但这是不必要的开销。 该表是固定的且很小，因此重复重新计算或解析它只会增加复杂性，而没有任何好处。 

关键的观察结果是，测试用例之间没有任何变化，并且除了选择正确的已知值之外不需要任何计算。 一旦我们认识到问题是直接索引任务，解决方案就简化为将 11 个缩写存储在数组中并返回`(n-1)`-th 元素。 

暴力破解的想法在优雅而不是速度方面失败了：它需要重新读取结构化文本或模拟解析逻辑，考虑到语句中的编码噪声，这是脆弱的。 直接索引方法稳健且最小。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力解析 | 每个查询 O(1) 但实现复杂 | O(1) | O(1) | 不必要|
 | 直接查找| O(1) | O(1) | O(11) | 已接受 |

 ## 算法演练

 1. 构建一个列表`abbr`包含按比赛版本排列的 11 个已知缩写。 该列表直接源自问题表，其中每个位置对应一个版本。 
2.读取整数`n`来自输入。 
3、输出`abbr[n - 1]`，从问题陈述中基于 1 的索引转换为数组表示中基于 0 的索引。 

### 为什么它有效

 竞赛版本形成固定的顺序，条目之间没有转换或依赖关系。 每个查询只是询问存储在该序列中已知位置的值。 因为映射是静态的并且是整个域的全部`1..11`，明确存储它可以保证正确性。 唯一需要的转换是调整索引，一旦处理完毕，查找就准确了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

abbr = [
    "FZU",
    "FNU",
    "FZU",
    "FZU",
    "FAFU",
    "HQU",
    "MJU",
    "XMUT",
    "QZNU",
    "JMU",
    "FZU"
]

n = int(input().strip())
print(abbr[n - 1])
```该解决方案按照竞赛版本的确切顺序对缩写序列进行硬编码。 这是有意为之的，因为数据集是由问题陈述本身确定的。 

唯一重要的实施细节是`n - 1`调整。 由于 Python 列表是零索引的，但问题将第一版定义为`1`，如果不减一，每个答案都会移动一位。 

## 工作示例

 考虑输入`1`。 算法读取`n = 1`和访问`abbr[0]`，即`"FZU"`。 这与第一版的组织者相匹配。 

现在考虑`2`。 该算法访问`abbr[1]`，返回`"FNU"`。 这对应于表中的第二版。 

| 步骤| n | 使用索引 | 价值|
 | ---| ---| ---| ---|
 | 示例1 | 1 | 0 | 福州大学 |
 | 示例2 | 2 | 1 | 威尼斯师范大学 |

 这些示例证实映射纯粹是位置性的，并且索引是唯一需要的转换。

 这些约束确保恒定时间查找就足够了。 即使输入稍微扩展，这种方法也将保持最佳状态，因为除了索引之外不需要任何计算。
