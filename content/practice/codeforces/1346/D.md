 ## 解决方案
 ## 问题理解

 我们得到一个无向连通图，其中顶点代表房间，边代表隧道。 每个隧道已经有一个固定的值，我们必须为每个房间分配一个值。 

该规则将房间和隧道紧密地联系在一起：对于两个房间之间的每条边，边值必须等于两个房间值中较小的一个。 一旦选择了房间值，每条边都会自动强制，因此我们唯一的自由就是房间值的分配。 

目标不仅是满足所有约束，而且是最小化房间价值的总和。 如果不存在分配，我们必须报告不可能。 

这些约束促使我们为每个测试用例提供线性或近线性解决方案。 所有测试的顶点和边总数最多为 200,000，因此任何每个测试用例甚至是二次的方法都会失败。 即使像通过全图扫描重复重新计算一致性之类的事情也太慢了。 我们需要一个基本上每次测试都通过一到两个图的结构。 

周期产生了一个微妙的问题。 在树上，约束从叶子向内干净地传播。 在循环图中，可能会出现相互冲突的要求：一个房间可能被迫以不一致的方式严格大于和等于不同的邻居。 没有全局传播的天真的贪婪分配很容易接受无效的配置。 

一个简单的失败案例是一个三角形，其中边缘强制执行不兼容的最小值。 例如，如果边要求 (1,2)=5、(2,3)=7、(1,3)=6，则房间 2 必须至少为 7，房间 1 至少为 6，但边 (1,2) 将要求 min(a1,a2)=5，这是不成立的。 局部分配策略将忽略这个矛盾，除非它在全局范围内传播约束。 

核心困难在于，每条边都约束其两个房间之间的下端点，并且这些约束必须在房间作为最小端点的所有可能方式上全局一致。 

## 方法

 一个蛮力的想法是将每个房间值视为未知整数，并尝试迭代地强制执行约束。 我们可以从所有未分配的房间开始，重复选择一条边，并尝试设置两个端点，以便最小值与所需的边权重相匹配。 这很快就会变得不明确：分配一个端点会影响其所有邻居，并且重新访问边缘可能会强制进行修改。 

在最坏的情况下，每次更新都会级联到整个图，我们最终可能会多次重新访问边。 这类似于具有潜在重复松弛的约束传播，由于循环反复收紧值而给出指数或至少二次最坏情况。 

关键的观察结果是，每个房间必须至少与每个入射边权重一样大，因为如果一个房间参与权重为 w 的边并且它是较小的端点，则该房间必须等于 w； 如果它是较大的端点，则另一个端点等于 w，强制较大的端点至少为 w。 因此，每个房间都有一个自然下限：与其相关的最大边权重。 

令该下界为 L[i] = 接触 i 的边的最大权重。 最佳解决方案永远不会选择大于必要的值，因此我们首先设置 a[i] = L[i]。 

现在我们检查可行性：对于每条边 (u, v, w)，条件 min(a[u], a[v]) = w 必须成立。 由于两个端点都已经至少是其事件最大值，因此这简化为验证至少一个端点恰好是 w，而另一个端点至少是 w。 如果两个端点都严格大于w，则边缘无法达到其所需的最小值，因此配置无效。

因此，构造变为：为每个节点分配其最大关联边权重，然后验证所有边。 如果所有边都满足最小条件，则该分配是最优的； 否则不存在解决方案。 

这是有效的，因为将任何节点减少到其最大入射边权重以下会立即破坏该边，而将任何节点增加到其最大值以上只会不必要地增加总和。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力约束传播| 最坏情况 O(nm) | O(n + m) | 太慢/不稳定 |
 | 最佳最大分配+验证| O(n + m) | O(n + m) | 已接受 |

 ## 算法演练

 我们独立处理每个测试用例。 

1. 计算每个房间的所有与其相连的隧道中的最大重量。 该值表示仍然可以满足房间作为最小端点的任何边的最小可行分配。 任何较小的值都会立即违反至少一个约束。 
2. 为每个房间分配计算出的最大入射边权重。 此时，每个房间都设置为不会立即与局部边缘要求相矛盾的最小值。 
3. 检查每个隧道 (u, v, w) 并验证条件 min(a[u], a[v]) 等于 w 成立。 此步骤确保对于每条边，至少一个端点恰好是 w，而另一个端点不低于 w。 
4. 如果任何边不满足此条件，则输出 NO，因为没有任何调整可以在不破坏先前满足的约束的情况下修复它。 
5. 否则输出 YES，后跟所有分配的房间值。 

### 为什么它有效

 每个房间值都必须至少是与其相关的最大边权重，否则该边无法达到其所需的最小值。 将 a[i] 精确设置为该界限可以最小化总和。 

如果在此分配下边 (u, v, w) 无法满足 min(a[u], a[v]) = w，则两个端点都超过 w，这意味着在不违反另一个事件约束的情况下，两个端点都不允许下降到 w。 这意味着一个全局矛盾：每个候选任务都需要将至少一个端点降低到其自身事件最大值以下，根据构造的定义，这是不可能的。 这使得检查既必要又充分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        adj_max = [0] * n
        edges = []

        for _ in range(m):
            u, v, w = map(int, input().split())
            u -= 1
            v -= 1
            edges.append((u, v, w))
            if w > adj_max[u]:
                adj_max[u] = w
            if w > adj_max[v]:
                adj_max[v] = w

        a = adj_max[:]
        ok = True

        for u, v, w in edges:
            if min(a[u], a[v]) != w:
                ok = False
                break

        if not ok:
            print("NO")
        else:
            print("YES")
            print(*a)

if __name__ == "__main__":
    solve()
```该实现首先在读取边缘时构建每个节点所需的最大值，因此不需要额外传递邻接列表。 分配步骤只是复制这些最大值。 

验证循环至关重要，因为构造不能自动保证满足每条边的最小条件； 它只保证没有节点违反其最强的局部约束。 最终检查确保可能具有不对称最大值的边缘之间的一致性。

 ## 边缘情况

 一种重要的边缘情况是当一个节点具有多个具有不同权重的关联边时。 该构造将节点设置为最大值，这可以立即使较小的边失效。 例如，如果一个节点连接权重为 2 和 10，则它变为 10，并且权重为 2 的边只有在其另一个端点正好为 2 时才保持有效。 

另一种边缘情况是图是树时。 在这种情况下，构造总是成功的，因为每条边总是可以正确分配较小的端点，而不会出现循环强迫矛盾。 该算法自然会处理这个问题，因为当存在一致的树分配时，验证步骤永远不会失败。 

最后一种情况是所有边具有相同的权重。 每个节点都接收相同的值，并且每条边都满足最小条件。
