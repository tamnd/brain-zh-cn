 ## 解决方案
 ## 问题理解

 我们有一排书架，每个书架上放着一定数量的书。 目标是达到每个货架最多有`k`图书。 我们可以使用两个操作来修改配置。 第一个操作是本地的：我们可以选择一个书架并以一定的成本移除其所有书籍`x`。 第二个操作是全球性的：我们拿走所有书籍，然后以一定成本将它们尽可能均匀地重新分配到所有书架上`y`，生成一个值最多相差 1 的配置。 

任务是选择这些操作的顺序，以最小化总成本，同时确保最终配置遵循上限`k`。 

The key constraint is that`n`所有测试用例最多`2 * 10^5`，因此任何每个测试用例都是二次的解决方案都将失败。 甚至一个`O(n log n)`仅当我们仔细聚合时，每次测试才是可接受的，但重复模拟操作或探索子集是不可能的。 我们需要一个解决方案，将每个测试用例简化为线性或线性算术工作。 

当全局重新分配产生的值仍然超过`k`。 这种情况下，单靠操作是不够的，必须与清除相结合。 另一个棘手的情况是，移除几个大型货架比首先进行全球重新分配更昂贵，即使重新分配乍一看似乎很浪费。 

例如，考虑大多数值略高于`k`，但有一个值非常大。 简单的方法可能总是删除最大的元素，但有时单个全局重新分配会使所有值足够小，从而无需进行昂贵的删除操作。 

## 方法

 暴力策略将考虑架子的所有子集来应用第一个操作，并为每个子集决定是否在之前或之后应用第二个操作。 删除子集后，我们将计算是否需要重新分配并进行模拟。 这导致检查`2^n`子集，即使我们限制只删除“坏”货架，在最坏的情况下组合的数量仍然是指数级的。 

关键的观察是第二个操作的行为具有确定性：应用后，所有值都变为`floor(S/n)`或者`ceil(S/n)`在哪里`S`是总和。 这意味着我们永远不需要模拟任意状态。 我们只需要知道有多少货架超出`k`，以及在决定重新分配是否有益之前我们可能想要删除其中的多少。 

我们不是选择任意子集，而是对数组进行排序。 这让我们将移除视为“切除最大的元素”。 如果我们删除`i`最大的货架，我们可以计算剩余的金额并检查重新分配会产生什么。 这将每个测试用例的决策空间从指数候选减少到线性候选。 

然后我们比较两种策略：仅删除直到所有值 ≤ k，或者在删除最大元素的某些后缀后执行重新分配。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力子集 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 排序 + 尝试删除后缀 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 我们将问题简化为决定在可能应用重新分配之前删除多少个最大元素。 

1. 对数组进行非降序排序。 这确保了任何被删除元素的集合都对应于数组的后缀。 
2. 计算前缀和，以便我们可以快速得到删除后缀后剩余元素的总和。 
3.让`i`表示我们删除了多少个最大的元素。 最初，考虑`i = 0`。 
4. 对于每个`i`从`0`到`n`，计算剩余金额和剩余数量`m = n - i`。 
5、检查当前配置是否已经满足条件`max ≤ k`。 由于我们删除了最大的元素，这相当于检查`a[m-1] ≤ k`。 如果为真，则用成本更新答案`i * x`。 
6. 否则，请考虑在删除后执行全局重新分配。 计算重新分配的最大值，即`ceil(sum / m)`。 如果该值 ≤ k，则状态可以通过成本固定`i * x + y`。 
7. 取所有有效值中的最小值`i`。 

关键思想是删除仅针对最大的元素，因为任何最佳策略都不会在保留较大元素的同时删除较小的元素，因为这两种操作在位置方面是对称的，但在值方面却不是对称的。 

### 为什么它有效

 该算法依赖于这样一个事实：第二个操作破坏了排序，并将数组替换为仅由总和确定的近均匀分布。 这消除了在重新分配后跟踪各个元素的需要。 因此，在选择要丢弃多少个元素之后，唯一相关的状态是`(remaining count, remaining sum, maximum remaining element before redistribution)`。 排序确保每个有意义的删除配置都由后缀表示，因此我们不会错过任何最佳解决方案。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, x, y = map(int, input().split())
        a = list(map(int, input().split()))
        
        a.sort()
        
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]
        
        ans = float('inf')
        
        for rem in range(n + 1):
            i = n - rem  # number of removed largest elements
            if rem == 0:
                sum_rem = 0
            else:
                sum_rem = pref[rem]
            
            if rem > 0 and a[rem - 1] > k:
                continue
            
            cost = i * x
            
            if rem > 0:
                max_after = (sum_rem + rem - 1) // rem
                if max_after <= k:
                    ans = min(ans, cost + y)
            else:
                ans = min(ans, cost)
        
        print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先进行排序，以便删除最大的元素成为反向索引中的前缀切割。 前缀和允许对剩余和进行恒定时间计算。 该循环枚举删除后剩余的元素数量。 该部门`(sum_rem + rem - 1) // rem`计算重新分配后的最坏情况值。 

一个微妙的细节处理`rem = 0`，相当于删除所有元素。 在这种情况下，重新分配毫无意义，只有搬迁成本才重要。

 ## 边缘情况

 关键的边缘情况是所有元素都已经 ≤ k 时。 在这种情况下，每次循环迭代都应该允许零成本，并且任何强制执行至少一个操作的实现都会错误地增加成本。 该算法处理这个问题是因为`rem = n`产生零清除并且没有重新分配。 

当只有一个元素超过 k 时，会出现另一种边缘情况。 这里，正确的决定完全取决于是否`x`小于`y`，算法通过评估直接删除和删除后的重新分配来捕获这一点。 

最后一个微妙的情况是，即使平均值很小，重新分配也会产生略高于 k 的值。 上限运算至关重要，因为单独的整数除法会低估分配后的真实最大值。
