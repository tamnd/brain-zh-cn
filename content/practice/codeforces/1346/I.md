 ## 解决方案
 ## 问题理解

 游戏世界是一个有向图，最多有 15 个位置，每个位置包含固定数量的颗粒。 从任何位置都可以到达任何其他位置，因此该图是强连接的。 

吃豆人从给定的节点开始，每当到达某个节点时，它就会立即收集当前存在的所有颗粒。 一旦世界上的每个颗粒都被收集起来，所有节点都会被重新填充到原来的数量，并且这个过程可以无限期地继续下去。 我们唯一关心的“成本”是遍历了多少条有向边； 收集颗粒是免费的，并且仅沿着边缘移动会增加难度。 

每个查询都要求收集至少给定数量的颗粒所需的最小边缘遍历次数，假设在可能的多个填充周期中实现最佳播放。 

关键的困难在于玩家可以构建运动，以便在不同的周期中以不同的顺序收集颗粒，并且在每次完整收集后世界都会重置，从而使之前收集的节点再次变得有价值。 我们的目标不仅仅是找到一条最佳路线，而是有效地结合重复的“收集周期”以达到大量的颗粒。 

图形大小的约束非常严格，但查询和目标值的约束很大。 对于最多 15 个节点，任何以 n 为指数的解决方案都是合理的，但任何以查询数量或目标 C 为指数的解决方案都是不可能的。 这强烈建议节点上的子集 DP 与最短路径预计算相结合。 

一个微妙的边缘情况来自重置机制。 如果一种简单的方法假设全球每个节点只能收集一次颗粒，那么它将低估可实现的总数。 例如，如果一个周期内所有节点都被访问一次，则总奖励会重置并可以再次获得，因此最优解决方案通常会重复多次循环。 

另一种失败模式是将每次遍历视为独立于集合状态。 实际上，访问一个节点的好处取决于它是否已经在当前周期中被收集，因此状态必须跟踪自上次重置以来哪些节点已被访问。 

## 方法

 暴力策略将模拟图上所有可能的行走，跟踪自上次重置以来收集了哪些节点以及积累了多少颗粒。 每次访问一个节点时，如果当前周期中尚未收集该节点，则该节点会贡献其值，并且一旦所有节点都被收集，状态就会重置。 这导致了位置的状态空间与访问节点的子集和累积总数相结合。 即使忽略大目标 C，探索所有游走也会随着路径长度呈指数增长，并且循环使搜索不受限制。 

关键的观察结果是，因为 n 最多为 15，所以循环内唯一有意义的结构是自上次重置以来访问过的节点子集。 在一个周期内，两次访问同一节点不会带来额外的好处，因此每个周期都可以简化为从给定端点开始的某些节点子集的排列。 这将问题转化为旅行式子集 DP，我们计算收集从固定起点开始并在任意位置结束的节点子集的最佳方法。 

一旦我们能够计算出对于任何子集 S，在一个周期内准确收集 S 的最小遍历成本和总奖励，全局过程就变成了一系列独立的周期。 每个完整循环贡献一个固定奖励，等于所有 a[i] 的总和，部分循环贡献任何子集奖励。 查询的答案变成重复的完整循环加上一个最终部分循环的组合。

 ## 算法演练

 我们首先将问题分为“全循环”和“部分循环”。 

1. 使用 Floyd-Warshall 计算节点之间的全对最短路径。 无论中间结构如何，这都给出了任意两个节点之间的最小遍历成本。 这是必需的，因为在子集 DP 中，我们将以任意顺序在节点之间移动。 
2. 在子集上定义 DP，其中 dp[S][v] 表示从初始节点 s 开始、访问子集 S 中的每个节点一次（在我们第一次到达时收集其颗粒）所需的最小边遍历次数，并在节点 v 结束。 
3. 初始化 dp，仅包含起始节点。 如果 S = {s}，则 dp[S][s] = 0，因为我们从那里开始并立即收集其颗粒。 
4. 通过添加一个不在 S 中的新节点 u 进行转换。要计算 dp[S ∪ {u}][u]，请考虑 S 中所有可能的先前端点 v，并使用预先计算的最短路径距离将路径从 v 延伸到 u。 该转换添加了成本 dp[S][v] + dist[v][u]。 
5. 将奖励[S]计算为 S 中所有 i 的 a[i] 之和。这是该周期中收集的颗粒数量。 
6. 现在将每个子集状态解释为一个可能的“循环”：它提供了一种方法来收集某个端点 v 的奖励 [S] 颗粒，成本为 dp[S][v]。为了使循环可重复，我们在概念上允许再次使用最短路径返回到起点，但对于分解来说，单独处理完全完成就足够了。 
7. 设 A 为所有 a[i] 的总和。 一个完整的循环对应于S=所有节点，给予奖励A。一个完整循环的最小成本是最好的dp[ALL][v]加上dist[v][s]返回。 
8. 对于查询C，将其拆分为C = k·A + r。 我们支付 k 倍的全周期成本，因为每个全周期都可以独立重复。 
9. 对于剩余的r，我们只需要从s开始的一个部分循环。 我们考虑所有子集 S 和端点 v，并取最小 dp[S][v] 使得奖励[S] ≥ r。 

### 为什么它有效

 关键的不变量是任何最佳行走都可以分解为重置之间的最大分段。 每个段完全对应于自上次重置以来访问过一次的节点的子集，因为在同一段中访问节点两次不会带来任何好处。 因此，每个可行策略都是子集循环的串联，并且每个子集循环完全由（S，端点）表征。 一旦执行了这种分解，全局优化就减少为选择要采取多少个完整周期以及哪个最终子集周期来完成剩余部分。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

INF = 10**18

n, m, q, s = map(int, input().split())
s -= 1

a = list(map(int, input().split()))
A = sum(a)

dist = [[INF] * n for _ in range(n)]
for i in range(n):
    dist[i][i] = 0

for _ in range(m):
    v, u = map(int, input().split())
    v -= 1
    u -= 1
    dist[v][u] = 1

for k in range(n):
    for i in range(n):
        for j in range(n):
            if dist[i][k] + dist[k][j] < dist[i][j]:
                dist[i][j] = dist[i][k] + dist[k][j]

size = 1 << n

# dp[mask][v] = min cost starting at s, visiting mask, ending at v
dp = [[INF] * n for _ in range(size)]

dp[1 << s][s] = 0

for mask in range(size):
    if not (mask & (1 << s)):
        continue
    for v in range(n):
        if dp[mask][v] == INF:
            continue
        for u in range(n):
            if mask & (1 << u):
                continue
            nmask = mask | (1 << u)
            nd = dp[mask][v] + dist[v][u]
            if nd < dp[nmask][u]:
                dp[nmask][u] = nd

# full cycle cost
full_mask = (1 << n) - 1
full_cost = INF
for v in range(n):
    if dp[full_mask][v] < INF:
        full_cost = min(full_cost, dp[full_mask][v] + dist[v][s])

# best partial for each reward threshold
best = [INF] * (A + 1)

for mask in range(size):
    reward = 0
    for i in range(n):
        if mask & (1 << i):
            reward += a[i]
    if reward == 0:
        continue
    for v in range(n):
        if dp[mask][v] < INF:
            best[reward] = min(best[reward], dp[mask][v])

# suffix min so best[r] = min cost achieving at least r
for i in range(A - 1, 0, -1):
    best[i] = min(best[i], best[i + 1])

for _ in range(q):
    C = int(input())
    k = C // A
    r = C % A

    ans = k * full_cost
    if r > 0:
        ans += best[r]
    print(ans)
```该实现首先构建最短路径，以便节点之间的任何多步遍历都可以被视为单个成本。 然后子集 DP 构建从起始节点开始收集一组节点的所有方法，跟踪端点和访问掩码。 

全周期计算通过返回开始来关闭覆盖所有节点的子集，这捕获了重置后游戏的重复结构。 最后，奖励表被转换为后缀最小数组，以便每个查询都可以快速找到至少满足剩余颗粒要求的最便宜的子集。 

分成完整周期和最终部分周期使得预处理后可以在恒定时间内回答最多 10^5 个查询。 

## 工作示例

 考虑具有三个节点的示例图，其中不同的路径允许以不同的顺序访问节点。 DP 表通过从起始节点开始逐渐扩展子集来演化，始终使用最短路径距离而不是直接边进行扩展。 

对于像这样的子集`{1,3}`，该算法考虑了访问节点的两种顺序，并保留遍历成本较低的一个。 这是至关重要的，因为图是有向的，节点之间的最短路径可能会经过不在子集中的中间节点。 

在全周期计算中，一旦包含了所有节点，DP 就会确保我们以最便宜的方式返回到起始节点，从而有效地关闭循环。 

然后，查询处理步骤将重复的完整循环与满足剩余要求的最终部分子集组合起来。

 ## 边缘情况

 当最优策略从不需要除最后一个循环之外的部分循环时，就会出现关键的边缘情况。 在这种情况下，解决方案不得尝试在完整周期之间交错部分子集周期，因为这样做会违反复位结构。 分解为完整周期加上一个后缀周期可确保这种情况不会发生，因为任何中间重置都必然意味着所有节点的完成。 

另一个边缘情况是剩余部分的最佳子集不是最大奖励子集而是更便宜的中等子集。 后缀最小变换保证了如果较大的奖励子集比较小的奖励子集更便宜，则仍然会考虑所有较小的阈值。
