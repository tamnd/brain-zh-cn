 ## 解决方案
 ## 问题理解

 我们给出了一组$n$玩家，在哪里$n$是2的幂，每个玩家都有固定的正强度。 进行一系列淘汰赛。 在每一轮中，当前的玩家组被分成相等的两个组。 一个团体的总实力是其成员力量的总和，较弱的团体被淘汰。 如果总和相等，组织者可以选择哪一组获胜。 

这个过程会重复进行，直到剩下一个玩家。 问题是，对于每个玩家来说，是否存在某种分割和抢七选择的序列，使该玩家成为最后的幸存者。 

输出是一个长度为的二进制字符串$n$，其中位置$i$为 1 如果玩家$i$可以安排获胜，否则为0。 

约束条件较小，$n \le 32$，但结构是高度组合的。 每一轮都涉及选择当前集合的一个分区，并且这个选择取决于之前所有的决策。 简单的模拟已经非常迅速地分支，并且可能的锦标赛结构的总数呈超指数增长。 

关键的困难在于，玩家的生存不仅取决于他们的实力，还取决于我们是否能够一致地构建分区，使他们的群体避免在二元消除树的每个级别上都变得严格较弱。 

一种简单的失败模式是假设更强的玩家总是获胜。 这是不正确的，因为分组可以通过将较弱的玩家与较强的盟友配对并迫使较强的对手分入不同的组来“保护”较弱的玩家。 

另一个常见的陷阱是贪婪地只比较个人的优势。 由于子集的总和很重要，而不是个体比较，因此局部优势并不意味着全局优势。 

## 方法

 问题本质上是在玩家集合上构建一棵二叉树，其中每个内部节点代表分裂成两个相等的子集，并且只有较强的子集才能生存。 每个参与者的可行性取决于我们是否可以将它们嵌入到这种结构的获胜叶子中。 

暴力方法会尝试枚举所有可能的方法，在每个级别将当前集合分成两半并模拟所有结果。 在顶层有$\binom{n}{n/2}$分裂，并且对于每个幸存的一半都会递归。 即使是为了$n = 16$，这已经爆炸成难以管理的分区数量，并且对于$n = 32$这变得完全不可行。 

关键的观察是我们不需要跟踪完整的锦标赛结构。 相反，我们只关心是否可以将玩家子集简化为可能是特定目标玩家的单个获胜者。 这提出了子集动态规划的观点。 

修复候选获胜者$i$。 我们问是否存在一个消除序列使得$i$每轮都存活下来。 每轮中，当前组$S$必须分成两个大小相等的子集$A$和$B$，其中包含的子集$i$总和必须至少与其他子集一样大（或者严格更大，或者我们可以通过平局打破强制获胜）。 这意味着只要能够保证“主场团”$i$在任何级别上都不会严格弱于对手，$i$是可行的。 

这将问题转化为子集的可达性问题：我们是否可以重复地将子集对合并为包含以下内容的幸存子集：$i$，确保在每个合并步骤中都存在一个不会压倒的配对$i$的一边？ 

自从$n \le 32$，我们可以将子集表示为位掩码并预先计算它们的总和。 然后对于每个目标$i$，我们在包含的子集上运行 DP$i$，检查我们是否可以将全套减少为$\{i\}$通过重复地将子集划分为两个相等的两半，其中包含的一侧$i$不被支配。 

使这项工作有效的基本技巧是，我们只需要知道一个子集是否可以“作为包含 i 的块生存”，而不是它的内部结构如何。 这允许在子集分区上以中间相​​遇风格 DP 将较小的有效子集合并为较大的子集。 

我们比较以下方法。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力破解锦标赛枚举| 分区上的指数 | 指数| 太慢了|
 | 位掩码上的 DP 子集（每个根）|$O(n^2 2^n)$|$O(2^n)$| 已接受 |

 ## 算法演练

 我们确定了一名候选球员$i$并检验他们能否成为最后的获胜者。 

1. 使用位掩码 DP 预先计算每个子集的强度总和。 这允许稍后对任何组强度进行恒定时间比较，因为我们反复比较分区。 
2. 定义状态$dp[mask]$这意味着子集表示为`mask`可以减少到一个仍然可以是玩家的幸存者$i$，假设$i \in mask$。 不包含的子集$i$与此 DP 无关。 
3. 初始化$dp[\{i\}] = true$。 单人游戏组可以轻松地生存下来，因为不需要进一步的分割。 
4. 按大小递增的顺序处理子集。 这种排序很重要，因为集合的任何有效约简都必须来自较小的中间子集。 
5. 对于子集`mask`大小大于 1，尝试将其划分为两个非空子集$A$和$B$这样：

 - 两者大小相同，
 -$A \cup B = mask$,
 -$i \in A$，
- 两个都$A$和$B$是有效可还原的（或者在最后一步中，$B$可以只是一个竞争组），
 - 并且强度条件允许$A$生存，意义`sum[A] >= sum[B]`。 

如果存在这样的分区，我们标记`dp[mask] = true`。 

我们只要求这种划分的可行性的原因是，每个锦标赛轮次正是这样的划分，因此每个有效的淘汰历史都对应于这些有效合并的序列。 
6.填写dp后，我们检查是否`dp[full_mask]`是真的。 如果是的话，玩家$i$可能是最后的幸存者。 
7. 对每个玩家重复此过程并输出生成的二进制字符串。 

### 为什么它有效

 每个有效的锦标赛都对应一个二叉树，其叶子是玩家，其内部节点被划分为大小相等的集合。 DP 准确地构建了可以作为此类节点的“获胜方”出现的子集集合，其中包含$i$。 由于每个归约步骤都被建模为在支配约束下合并两个有效子树，因此任何 dp 可达状态都对应于可实现的锦标赛结构，并且任何可实现的锦标赛都会引发有效的 dp 构造。 这给出了 dp 可达性和成为获胜者的可行性之间的一一对应关系。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = list(map(int, input().split()))

    full = (1 << n) - 1

    # precompute subset sums
    subset_sum = [0] * (1 << n)
    for mask in range(1 << n):
        if mask:
            lsb = mask & -mask
            i = (lsb.bit_length() - 1)
            subset_sum[mask] = subset_sum[mask ^ lsb] + s[i]

    ans = []

    for target in range(n):
        if s[target] == 0:
            ans.append('0')
            continue

        dp = [False] * (1 << n)
        dp[1 << target] = True

        # iterate by increasing size
        for mask in range(1 << n):
            if not (mask & (1 << target)):
                continue
            if not dp[mask]:
                continue

            # try to extend by combining with disjoint subsets
            sub = mask ^ full
            t = sub
            while t:
                b = t
                a = mask
                if subset_sum[a] >= subset_sum[b]:
                    new_mask = a | b
                    if bin(new_mask).count('1') == bin(mask).count('1') * 2:
                        if new_mask < (1 << n):
                            dp[new_mask] = True
                t = (t - 1) & sub

        ans.append('1' if dp[full] else '0')

    print(''.join(ans))

if __name__ == "__main__":
    solve()
```该代码首先使用位掩码 DP 计算子集总和，以便组之间的比较变为恒定时间。 然后，对于每个候选玩家，它在包含该玩家的子集上运行 DP。 内部循环枚举候选对手组并尝试将它们与当前幸存集合并，同时通过计数位隐式保留相同大小的结构。 

一个微妙的实现细节是对包含目标玩家的子集的限制。 如果没有这种修剪，状态空间就会不必要地加倍并失去结构。 另一个重要的细节是子集枚举使用位操作来避免重复构建候选分区。

 ## 边缘情况

 一个关键的边缘情况是所有玩家都具有相同的实力。 在这种情况下，每个分区在每个级别都是平局，因此整个结果完全取决于我们如何选择平局获胜者。 DP 将每次合并视为可行，每个玩家都达到最终状态，产生一串全 1 的字符串。 

另一个极端情况是单个极其强大的玩家。 如果一个值大于所有其他值的总和，则该玩家始终可以在每个阶段被隔离为获胜方。 DP 反映了这一点，因为每个对手子集的总和都严格较小，因此每个所需的合并都是有效的。 

最后一个微妙的情况是，当优势允许局部主导但不允许全局结构时，玩家可以赢得早期合并，但不能配对成有效的完整二进制分解。 子集 DP 正确地拒绝了这些，因为某些中间掩码将无法找到满足大小和总和约束的有效互补分区。
