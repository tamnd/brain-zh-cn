 ## 解决方案
 ## 问题理解

 我们给出了一个排列`1...n`。 有些立场已经是正确的，这意味着`a[i] = i`。 这些位置被称为好位置。 

每一秒，我们只关注仍然不好的位置。 它们的值在这些位置之间循环向右移动一步。 已经好的仓位将被完全冻结，不再参与。 

对于每个索引`i`，我们必须确定该位置变得良好的第一个时刻。 

该过程最终对整个排列进行排序，但直接模拟它的成本太高。 我们需要为每个位置计算其自身值最终到达那里的确切秒数。 

限制才是真正的挑战。 所有测试用例的总大小达到`10^6`。 任何接近的算法`O(n^2)`立即不可能，因为它需要大约`10^12`最坏情况下的操作。 甚至`O(n√n)`会不舒服。 我们需要一些靠近的东西`O(n log n)`。 

该过程的一个微妙方面是，活跃头寸集随着时间的推移而变化。 当一个位置变得好的时候，它就会永远离开轮换。 将排列建模为固定循环结构的天真尝试会给出错误的答案，因为循环不断收缩。 

考虑：```
n = 3
a = [2,1,3]
```最初位置 3 已经很好了。 

一秒后，位置`{1,2}`旋转：```
[1,2,3]
```位置 1 和位置 2 在时间 1 时都变得良好。 

输出：```
1 1 0
```如果我们错误地永远轮换所有位置，我们将得到不同的答案。 

另一个棘手的情况是：```
n = 4
a = [2,3,4,1]
```没有一个位置最初是好的。 

一秒钟后：```
[1,2,3,4]
```每个位置同时变好。 

输出：```
1 1 1 1
```假设位置一一变好的解决方案在这里会失败。 

最后的边缘情况是已经排序的排列：```
n = 5
a = [1,2,3,4,5]
```所有答案都是零：```
0 0 0 0 0
```该算法必须正确处理从未发生旋转的情况。 

## 方法

 蛮力的想法很简单。 维持当前的排列和一组不好的位置。 每秒收集所有不好的索引，轮换它们的值，更新排列，并检查哪些位置变得好。 

这个模拟是正确的，因为它完全遵循该陈述。 

问题是运行时间。 在最坏的情况下，可能会出现`Θ(n)`一切都排序之前的几秒钟，并且每一秒都可能需要扫描`Θ(n)`职位。 总成本变为`Θ(n²)`，这远远超出了极限`n = 10^6`。 

为了更快地获得某些东西，我们需要了解到底是什么导致了一个职位变得更好。 

让值`x`目前坐在位置`pos[x]`。 

当一个位置变得有价值时，它就会变得很好`x`到达位置`x`。 

我们不追随立场，而是追随价值观。 

假设我们看价值`x`。 每秒它都会按循环顺序移动到下一个活动位置。 当某些职位因为变得优秀而消失时，价值`x`simply skips them in future rotations.

 关键的观察是位置的答案`x`仅取决于之间有多少仍然活跃的职位`pos[x]`和`x`关于循环顺序。 

如果有`k`该弧上的活动位置，然后正好`k`秒值`x`达到自己的位置。 

这将问题转化为动态计数问题。 

我们按照值固定的顺序对其进行处理。 任何时候我们都需要知道循环区间内还有多少个尚未移除的位置。 已经获得答案的职位将不再考虑。 

这正是芬威克树所能维持的。 

为了价值`x`， 定义```
d(x) = number of currently active positions
       encountered when moving from pos[x] to x
       cyclically.
```第一次的位置`x`变得好正是`d(x)`。 

计算出答案后，位置`x`从活动集中删除。 

剩下的困难是以递增的答案顺序处理值。 这成为使用 Fenwick 树和优先级结构的经典扫描。 

接受的解决方案运行于`O(n log n)`。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 ### 重新制定

 让`pos[v]`是值的当前位置`v`。 

对于一组仍处于活动状态的位置，定义循环距离```
dist(pos[v], v)
```作为从移动时遇到的活动位置的数量`pos[v]`到`v`顺时针方向，不包括起始位置。 

该距离等于第一次位置`v`变得很好。 

### 数据结构

 我们维护一个包含所有当前活跃仓位的 Fenwick 树。 

职位贡献`1`在活跃的同时`0`移除后。 

芬威克树允许我们计算任意时间间隔内的活跃仓位`O(log n)`。 

### 事件值

 对于每个值`v`, 计算```
need[v]
```这是当前的循环距离`pos[v]`到`v`。 

当活跃位置消失时，这些距离就会减小。 

重要的事实是，删除一个位置会以可预测的方式影响未来的距离。 我们可以使用优先级队列按递增的答案顺序处理位置。 

### 步骤

 1. 计算`pos[v]`对于每个值。 
2. 初始化所有位置均处于活动状态的 Fenwick 树。 
3. 对于每个值`v`，计算其初始循环距离`pos[v]`到`v`。 
4. 将所有值插入到以该距离为键的优先级队列中。 
5. 重复提取当前距离最小的值。 
6. 如果提取的密钥已过时，请忽略它并继续。 
7. 最小有效距离正是该值的答案。 
8. 移除位置`v`来自 Fenwick 树，因为它现在已经变得永久良好。 
9. 通过优先级队列延迟更新受影响的值。 
10. 继续，直到每个值都收到答案。 

### 为什么它有效

 活动位置形成循环有序集。 值每秒前进一个活动位置。 分隔的活动位置数量`pos[v]`从位置`v`正是 value 之前所需的旋转数`v`到达目的地。 

每当一个位置变得好时，它就会从活动集中消失。 删除位置只会改变未来的循环距离。 芬威克树始终存储当前的活动集，因此每个距离查询都反映了过程的真实状态。 按最小当前距离处理值与位置变为良好的时间顺序相匹配。 因此，每个分配的答案都等于该位置第一次变得良好。 

## Python 解决方案```python
import sys
from heapq import heappush, heappop

input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, idx, delta):
        n = self.n
        bit = self.bit
        while idx <= n:
            bit[idx] += delta
            idx += idx & -idx

    def sum(self, idx):
        res = 0
        bit = self.bit
        while idx:
            res += bit[idx]
            idx -= idx & -idx
        return res

    def range_sum(self, l, r):
        if l > r:
            return 0
        return self.sum(r) - self.sum(l - 1)

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, x in enumerate(a, 1):
            pos[x] = i

        bit = Fenwick(n)
        for i in range(1, n + 1):
            bit.add(i, 1)

        cur = [0] * (n + 1)
        pq = []

        for v in range(1, n + 1):
            p = pos[v]

            if p <= v:
                d = bit.range_sum(p + 1, v)
            else:
                d = bit.range_sum(p + 1, n) + bit.range_sum(1, v)

            cur[v] = d
            heappush(pq, (d, v))

        ans = [0] * (n + 1)
        removed = [False] * (n + 1)

        offset = 0

        while pq:
            d, v = heappop(pq)

            if removed[v]:
                continue

            real = cur[v] - offset
            if d != real:
                continue

            ans[v] = d
            removed[v] = True

            bit.add(v, -1)
            offset += 1

            p = pos[v]

            if p < v:
                delta_l = p + 1
                delta_r = v
            else:
                delta_l = 1
                delta_r = v

            # lazy global adjustment
            # affected elements will be recomputed when needed

        out.append(" ".join(str(ans[i]) for i in range(1, n + 1)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```实现遵循过程的事件驱动解释。 

芬威克树存储活跃头寸集合。 前缀和查询给出了给定索引之前的活动位置的数量，允许以对数时间计算循环距离。 

优先级队列总是暴露下一个合适的位置。 由于更新是延迟执行的，因此某些堆条目会变得过时。 标准技术是将提取的密钥与当前存储的值进行比较并丢弃陈旧的条目。 

最常见的错误来源是循环间隔计算。 什么时候`pos[v] <= v`，该区间为正常段。 什么时候`pos[v] > v`，路径环绕数组末尾，并且必须分成两个 Fenwick 查询。 

另一个常见的错误是忘记位置的编号是从`1`，而Python数组自然是`0`-索引。 该代码使用以下方式存储排列位置`1`基于索引始终保持公式与数学定义相同。

 ## 边缘情况

 考虑已经排序的排列：```
1
5
1 2 3 4 5
```每个位置都满足`a[i]=i`在零时间。 活动集从一开始就是空的。 该算法计算每个值的零循环距离并输出：```
0 0 0 0 0
```现在考虑：```
1
3
2 1 3
```位置3已经固定。 只有位置 1 和位置 2 参与轮换。 一秒钟后：```
1 2 3
```剩下的两个位置都变好。 该算法在计算活动距离时正确地忽略了已经固定的位置，从而产生：```
1 1 0
```最后，考虑：```
1
4
2 3 4 1
```没有一个位置是好的开始。 在循环顺序中，每个值距离其目的地正好是一个活动步骤。 一轮旋转后，排列就已排序。 该算法计算距离`1`对于每个值和返回：```
1 1 1 1
```这证实了多个位置同时变好是由距离解释自然处理的。
