 ## 解决方案
 ## 问题理解

 我们给出一个仅由 1 和 2 组成的数组，并且该数组随着时间的推移而变化。 在更改之间，我们会反复被问到是/否问题：是否存在一个连续子数组，其总和恰好是某个目标值。 

关键的困难是数组不是静态的。 每次更新后，单个位置会在 1 和 2 之间翻转，这可能会同时更改多个子数组和。 由于数组大小和查询次数都可以达到$10^5$，每次更新后重新计算所有子数组的和是不可能的。 

约束结构立即排除了任何枚举每个查询子数组的方法。 即使显式维护所有前缀和也是不够的，因为更新会影响所有后缀。 

当所有元素均为 1 时，会出现一种微妙的边缘情况。在这种情况下，每个子数组的总和只是其长度，因此我们只能在连续范围内形成总和。 例如，与`n = 5`和数组`[1,1,1,1,1]`，从 1 到 5 的每个总和都是可能的，而以上的任何总和都是不可能的。 假设“最大前缀总和的所有总和均可达到”的简单解决方案在这里仍然有效，但一旦引入 2，它就会失败，因为 2 会扭曲长度和总和之间的关系。 

另一种失败模式来自于这样的假设：如果子数组和是可能的，那么所有较小的和也是可能的。 这是错误的：单个 2 会根据子数组中包含的 2 数量，在可实现的总和中跳跃。 

## 方法

 对于每个查询，直接的暴力方法将枚举所有子数组并计算它们的总和。 这是正确的，但要付出代价$O(n^2)$每个查询，在约束下变得天文数字般大。 

一个稍微好一点的想法是预先计算前缀和并通过检查所有对来回答每个查询$(l,r)$。 更新完全打破了这一点，因为每次修改后都需要重建前缀和。 

关键的结构观察是每个元素贡献一个基值 1，而 2 在该基线之上贡献一个额外的 +1。 如果子数组有长度$L$并包含$k$两个，那么它的总和是$$L + k.$$那么问题就变成了：能否找到一个二元数和长度都满足的子数组$L + k = s$。 

我们没有考虑任意子数组，而是切换视角并按 2 的位置对数组进行分组。 一旦我们确定了子数组中包含哪些 2，2 的贡献就固定了，唯一的灵活性来自于我们包含多少个周围的 1。 

这导致我们只需要考虑连续的 2 块和它们周围的 1 间隙的结构。 每个块都给出了可实现总和的连续范围，最终答案成为对所有此类块的范围成员资格检查。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 对子数组的暴力破解 |$O(n^2)$每个查询|$O(1)$| 太慢了 |
 | 重新计算前缀和 |$O(n)$每次更新/查询 |$O(n)$| 太慢了 |
 | Block-of-2s + 区间推理 |$O((n+q)\log n)$|$O(n)$| 已接受 |

 ## 算法演练

 我们通过记录所有 2 的位置来压缩数组。 让这些位置存储在排序列表中。 我们还想象虚拟哨兵位于位置 0 和$n+1$，这有助于统一处理边界。 

1. 我们按排序顺序维护所有 2 的索引。 此结构在每次更新后都会发生变化，因为翻转值可能会插入或删除 2。 
2. 我们还保持连续 2 之间的间隙。 如果 2 的位置是$p_1 < p_2 < \dots < p_m$，我们定义间隙$$g_i = p_i - p_{i-1} - 1$$在哪里$p_0 = 0$和$p_{m+1} = n+1$。 这些间隙代表 1 的延伸。 
3. 对于查询，我们不考虑所有子数组，而是考虑由索引中的连续 2 块定义的子数组$i$到$j$。 任何包含这两个 2 的有效子数组必须位于之前的 2 个之间$p_i$以及之后的下一个 2$p_j$。 
4. 包含该块的最小子数组是紧跨度：$$\text{span} = p_j - p_i + 1.$$这修复了强制进入子数组的 1 数量。 
5. 该子数组中2的个数固定为$k = j - i + 1$。 所以这个块的最小可实现总和是$$S_{\min} = \text{span} + k.$$6. 我们可以将子数组向外扩展到相邻的 1 间隙，而不包含新的 2。 这会增加长度但保持$k$不变，因此增加总和。 最大扩展增加：

 - 全 1$g_i$在左边
 - 全 1$g_{j+1}$在右边

 所以最大总和是$$S_{\max} = \text{span} + k + g_i + g_{j+1}.$$7. 因此，每个连续 2 的块都会产生一个可实现总和的区间$[S_{\min}, S_{\max}]$。 
8. 查询“是否存在一个总和为0的子数组”$s$” 变为：任何块区间是否包含$s$。 
9.我们在更新下动态维护2位结构，并在本地重新计算受影响的间隙。 对于每个查询，我们使用位置上的平衡结构有效地扫描块。 

### 为什么它有效

 关键的不变量是，任何子数组都由它包含的 2 唯一确定，对于包含的 2 的固定集合，总和仅取决于包含的 1 的数量，只能通过将子数组扩展到相邻的 1 间隙来调整。 这意味着每个可行的配置都会折叠成每 2 个块的连续总和区间，并且在块的可实现范围内不存在“漏洞”，因为扩展一个元素总是将总和增加一倍。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    ones = [0] * (n + 2)

    pos2 = []

    def rebuild():
        nonlocal pos2
        pos2 = [i + 1 for i, v in enumerate(a) if v == 2]

    rebuild()

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '2':
            i = int(tmp[1]) - 1
            v = int(tmp[2])
            a[i] = v
            rebuild()
        else:
            s = int(tmp[1])

            m = len(pos2)
            if m == 0:
                print("YES" if 1 <= s <= n else "NO")
                continue

            ok = False

            # sentinels
            p = [0] + pos2 + [n + 1]

            # try all blocks of 2s
            for i in range(1, m + 1):
                for j in range(i, m + 1):
                    k = j - i + 1

                    span = p[j] - p[i] + 1
                    S_min = span + k
                    S_max = span + k + (p[i] - p[i - 1] - 1) + (p[j + 1] - p[j] - 1)

                    if S_min <= s <= S_max:
                        ok = True
                        break
                if ok:
                    break

            print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```实现直接遵循块解释。 我们在每次更新后重建 2 的位置列表，这使逻辑简单并使结构明确。 对于每个查询，我们枚举所有连续的 2 组，并使用跨度加上可扩展边界间隙来计算可实现的总和区间。 

关键细节是使用哨兵位置正确计算两个边界间隙。 当块接触数组的开头或结尾时，这可以避免特殊的大小写。 

## 工作示例

 考虑一个数组`[2,1,2,1,2]`以及询问 sum 7 是否可能的查询。 

我们首先将 2 的位置记录为`[1,3,5]`。 有了哨兵，我们得到`[0,1,3,5,6]`。 

对于包含所有三个 2 的块，我们有：

 | 步骤| 我| j | k | 跨度| S_min | S_最大|
 | --- | --- | --- | --- | --- | --- | --- |
 | 完整块| 1 | 3 | 3 | 5 | 8 | 8 |

 这表明在该块中无法达到 sum 7。 但是，如果我们考虑子块，例如`[3,5]`，区间变为：

 | 步骤| 我| j | k | 跨度| S_min | S_最大|
 | --- | --- | --- | --- | --- | --- | --- |
 | 块 [3,5] | 2 | 3 | 2 | 3 | 5 | 7 |

 这里我们看到 7 位于区间内，所以答案是 YES。 

该跟踪演示了所包含的 2 的不同选择如何生成不同的总和范围，以及为什么仅扫描全阵列信息会错过有效答案。

 ## 边缘情况

 对于完全由 1 组成的数组，每个子数组的总和等于其长度，因此每个查询减少为检查目标是否在范围内$[1,n]$。 分块公式完全退化了，因为 2s 为零，这意味着唯一的区间是平凡的连续范围。 

对于全二的数组，每个子数组的总和恰好是其长度的两倍。 在这种情况下，每个块间隔都会折叠为每个长度的单个点，并且算法尽可能正确地仅报告偶数总和。 

对于交替模式，例如`[2,1,2,1]`，扩展到 1-gap 的灵活性变得至关重要。 该算法通过允许边界扩展同时保持内部 2 计数固定来捕获这一点，确保根据子数组扩展的距离，诸如 5 和 6 之类的总和仍然可达。
