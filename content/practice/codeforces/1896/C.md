 ## 解决方案
 ## 问题理解

 我们有两个长度相等的数组。 大批`a`是固定的，而数组`b`可以任意重新排列。 选择排列后`b`，我们逐个位置比较数组。 

生成的数组对的美妙之处在于索引的数量，其中`a[i] > b[i]`。 

For each test case, we are given a target value`x`。 任务是判断是否存在排列`b`谁的美丽正是`x`。 如果存在这样的排列，我们必须输出一种有效的排列。 

所有测试用例的总大小最多为`2 · 10^5`。 这立即排除了任何检查许多排列的情况。 甚至一个`O(n²)`算法将执行大约`4 · 10^10`最坏情况下的操作，远远超出了极限。 自排序以来`2 · 10^5`数字很​​容易负担得起，解决方案`O(n log n)`每个测试文件是自然目标。 

棘手的部分是我们没有最大化或最小化美丽。 我们需要一种安排来精确产生给定数量的获胜位置。 

一个容易犯的错误是贪婪地分配较小的值`b`尽可能停止一次`x`胜利已被创造。 

考虑：```
n = 3, x = 1
a = [2, 4, 3]
b = [4, 1, 2]
```一个粗心的贪婪者可能会放置`1`反对`4`，创造一场胜利，然后任意分配剩余的值。 它可能会意外地创造第二次胜利。 正确答案是存在的：```
b = [2, 4, 1]
```这恰好产生一个获胜位置。 

当所要求的美感不可能实现时，就会出现另一种微妙的情况。```
n = 1, x = 1
a = [1]
b = [2]
```不存在重新排列。 自从`1 > 2`是假的，美丽永远为零。 

错误的第三个来源来自于相同的值。```
n = 3, x = 0
a = [2, 2, 2]
b = [2, 2, 2]
```美只取决于严格的不平等。 同等价值没有贡献。 任何处理的逻辑`>=`因为胜利会产生错误的答案。 

## 方法

 蛮力方法很简单。 生成每个排列`b`，计算每个排列的美丽度，并检查是否有任何美丽度等于`x`。 

美度计算需要`O(n)`时间。 有`n!`排列。 即使是为了`n = 10`，这已经是关于`3.6 million`排列。 为了`n = 20`，它变得完全不可行。 由于实际限制是`2 · 10^5`，蛮力仅对理解问题的结构有用。 

关键的观察结果是，只有值的相对顺序才重要。 假设我们对位置进行排序`a`按价值。 如果我们想要确切地`x`位置，其中`a[i] > b[i]`，那么最小的`x`的值`b`应该用来创造这些胜利，因为小值最容易被击败。 

让我们对索引进行排序`a`通过增加`a[i]`。 令这些指数为：```
p[0], p[1], ..., p[n-1]
```同时对以下值进行排序`b`。 

准确地创建`x`获胜，分配最小的`x`已排序的元素`b`到最大的`x`的元素`a`。 

为什么？ 那些最大的元素`a`是最容易保证的地方`a[i] > b[i]`。 

完成该任务后，剩余的`n - x`的值`b`被分配到剩余位置`a`。 

出现一个非常优雅的结构。 如果排序`b`是：```
b0 ≤ b1 ≤ ... ≤ b(n-1)
```然后对位置进行排序后`a`，我们放置：```
b0 ... b(x-1)
```到最大的`x`的职位`a`， 和```
bx ... b(n-1)
```到最小的`n-x`职位。 

这相当于旋转已排序的`b`数组依据`x`相对于排序的位置`a`。 

由此产生的排列要么恰好给出`x`获胜或证明不存在解决方案。 我们只是事后计算实际的美丽。 如果计数等于`x`，我们输出排列。 否则，不存在有效的安排。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n·n!) | O(n·n!) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 对索引进行排序`a`通过增加价值。 
2. 对所有值进行排序`b`。 
3. 创建一个长度为answer的数组`n`。 
4.对于最小的`n - x`按排序顺序排列的位置`a`，分配最大的`n - x`已排序的值`b`。 

更准确地说，对于`i = 0 ... n-x-1`:```
ans[pos[i]] = sorted_b[x + i]
```这些职位应尽可能避免创造胜利。 
5.对于最大的`x`按排序顺序排列的位置`a`，分配最小的`x`已排序的值`b`。 

为了`i = 0 ... x-1`:```
ans[pos[n-x+i]] = sorted_b[i]
```这些是旨在成为胜利的位置。 
6. 计算构造排列的美感。 
7.如果美丽等于`x`， 打印`"YES"`以及安排。 
8. 否则打印`"NO"`。 

### 为什么它有效

 对两个数组进行排序后，构造对最小的`x`的元素`b`最大的元素为`a`。 如果有什么安排可以创造`x`获胜位置，这些是最有利于获胜的位置。 

其余较大元素`b`与较小的元素相匹配`a`，最大限度地减少创造额外胜利的机会。 

这种安排是官方解决方案中使用的标准循环移位结构。 如果可以实现所需的美感，那么建筑就会实现它。 如果建筑所产生的美感不完全是`x`，那么通过任何排列都无法获得所需的获胜次数。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        pos = sorted(range(n), key=lambda i: a[i])
        b.sort()

        ans = [0] * n

        for i in range(n - x):
            ans[pos[i]] = b[x + i]

        for i in range(x):
            ans[pos[n - x + i]] = b[i]

        beauty = sum(a[i] > ans[i] for i in range(n))

        if beauty == x:
            print("YES")
            print(*ans)
        else:
            print("NO")

solve()
```第一步对索引进行排序`a`而不是排序`a`本身。 我们最终需要按原始顺序输出排列，因此跟踪位置至关重要。 

两个赋值循环实现循环移位。 第一个循环填充较小的元素`a`大部分已排序`b`。 第二个循环放置最小值`b`的最大值`a`。 

构建候选排列后，代码执行直接验证。 最后的检查很重要，因为相等值的存在可能会阻止某些预期获胜位置实际满足`a[i] > b[i]`。 

验证步骤仅`O(n)`，因此不会影响整体复杂度。

def run(inp: str) -> str:

 ## 边缘情况

 考虑：```
1
1 1
1
2
```排序后的数组保持不变。 该建筑产生：```
ans = [2]
```美是：```
1 > 2 = false
```美丽在于`0`， 不是`1`，所以算法打印`"NO"`。 

现在考虑相等的值：```
1
3 0
2 2 2
2 2 2
```排序后，每个作业仍然放置`2`反对`2`。 

美变成：```
0
```因为平等并不算是胜利。 验证步骤正确接受安排。 

最后考虑：```
1
3 3
2 4 3
4 1 2
```该结构将最小值`b`针对最大的值`a`，试图创造三场胜利。 由此产生的排列包含一个位置：```
4 vs 4
```这不是胜利。 美变成`2`。 最终验证检测到不匹配并输出`"NO"`。 

这些示例说明了为什么验证步骤是必要的。 该结构确定了唯一可以实现目标美感的候选排列，最后的计数确认了它是否确实实现了。
