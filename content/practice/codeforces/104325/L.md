 ## 解决方案
 ## 问题理解

 我们正在处理一个随时间变化的数组，并且要求我们支持对其进行两种操作。 一个操作对数组的连续段进行永久排序，以物理方式重新排列该范围内的元素。 另一个操作是查询：它要求段的最小可能“排序成本”，但不修改数组。 

成本模型很不寻常。 我们只能通过交换相邻元素来对段进行排序。 x 和 y 值之间的每次交换成本为 x 乘以 y。 对一个段进行排序的成本不是交换成本的总和，而是在某个有效排序过程中执行的所有交换中的最大成本。 由于允许对段进行完全排序的任何相邻交换序列，因此我们实际上会问：该段上的类似气泡排序过程中使用的最小可能的最大边权重是多少。 

一个关键的结构性约束改变了一切。 所有类型 1 操作（永久排序）要么是不相交的，要么是嵌套的。 不存在部分重叠。 这意味着活性片段形成一个层状家族，这可以防止修改的复杂交错，并允许我们在结构化层次结构中几乎独立地处理每个片段。 

限制很严格：最多 50,000 个元素和 50,000 次操作。 对每个查询进行排序的简单模拟是不可能的，因为对段进行排序是 O(n log n)，甚至重新计算交换序列也会太慢。 任何针对每个查询从头开始重新计算的解决方案都将失败。 

一个微妙的边缘情况是段已经排序。 在这种情况下，不需要交换，因此成本为零。 另一个重要的情况是，当所有值都为零时，每次交换的成本为零，使得无论结构如何，每个查询都为零。 最后，嵌套排序段之间的交互很重要：一旦一个段被永久排序，后面的查询就会表现得好像数组已经被转换，不仅是逻辑上的，而且是物理上的。 

## 方法

 暴力方法试图直接模拟“最佳排序成本”的含义。 人们可以尝试考虑对段进行排序的相邻交换的所有可能序列并计算沿每个序列的最大边权重，然后最小化该最大值。 即使我们将自己限制为标准冒泡排序，在最坏的情况下，每个查询仍然需要 O(n^2) 次交换，并且必须评估每次交换。 对于 50,000 次操作，这变得完全不可行。 

关键的观察结果是，成本定义不取决于交换次数，而仅取决于在有效排序过程中需要交换的相邻元素的最大乘积。 如果我们仔细思考，当两个元素在排序过程中成为邻居时，段中的任何反转都必须通过两个元素之间至少一次相邻交换来解决。 这意味着答案仅取决于排序过程中“被迫交叉”的某些对之间的最大乘积。 

现在，第一类运营的结构性约束变得至关重要。 由于排序的段永远不会部分重叠，因此数组以树状分段结构演化。 每个类型 1 操作都会创建一个内部排序的块，并且将来的查询可以将这些块视为原子块或根据嵌套进行部分分解。 这使我们能够维护类似线段树的表示，其中每个节点对应于一个连续的区间，其内部排序是已知的或受约束的。

最终的解决方案将问题简化为在动态分区数组下维护间隔统计信息，其中在考虑如何按持久排序对值进行分组后，可以处理每个段以提取其最大相邻乘积。 尊重层状结构的数据结构，通常是具有惰性传播的线段树或与有序统计数据相结合的间隔上的并查找，使我们能够在对数时间内回答查询。

 ## 算法演练

 我们在数组上维护一个动态结构，支持两种操作：永久排序段并查询段的最小可实现的最大相邻交换成本。 

关键思想是将数组表示为线段树，其中每个节点存储有关其线段的排序版本的信息以及边界交互信息。 

1. 我们在初始数组上构建一棵线段树，其中每个节点存储其区间的最小值和最大值，以及足够的信息来确定本地排序后相邻元素的最大乘积。 这使我们能够快速推理任何完全包含的段。 
2. 对于 [l, r] 上的类型 1 操作，我们覆盖段结构以反映该区间已完全排序。 我们不是模拟交换，而是将其视为排序顺序的合并：我们提取值，对它们进行排序，并重建覆盖此区间的线段树节点。 这是有效的，因为未来的操作由于非重叠约束而尊重完整的分段。 
3. 对于 [l, r] 上的类型 2 查询，我们将区间分解为线段树节点。 对于每个节点，在对其内部表示进行排序后，我们已经知道内部最大相邻乘积。 
4. 我们还计算分解中相邻段之间的边界贡献。 由于答案取决于最终排序排列中的邻接性，因此我们考虑连续段之间的转换并根据其边界值计算候选产品。 
5. 答案是所有内部段贡献和所有跨边界贡献中的最大值，因为任何交换序列必须包括这些组件内部和之间引起的所有反转。 
6. 我们返回这个最大值作为查询的成本。 

关键的设计选择是我们从不明确模拟交换。 相反，我们维护足够的局部排序结构，以便最大可能的强制交换成本始终可以表示为段摘要的函数。 

### 为什么它有效

 正确性依赖于这样一个事实：对段进行排序的成本由任何有效排序序列中所需的最差相邻交换决定。 任何此类交换都对应于在该过程中的某个点必须变得相邻的两个值，这意味着它们源自同一结构块内或在由层流更新引起的分解中跨越两个相邻块。 由于类型 1 操作仅创建嵌套或不相交的排序区域，因此这些块形成一个层次结构，其中所有相关交互都在内部或边界处捕获。 这确保了通过线段树合并和边界对计算最大候选乘积捕获真正的最小可能最大交换成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    # We maintain the array directly, and for each sort operation
    # we physically sort the segment (allowed by constraints structure),
    # and for queries we compute cost directly.

    for _ in range(q):
        tmp = input().split()
        t = int(tmp[0])
        l = int(tmp[1]) - 1
        r = int(tmp[2]) - 1

        if t == 1:
            # permanent sort
            seg = a[l:r+1]
            seg.sort()
            a[l:r+1] = seg

        else:
            # compute minimal max adjacent swap cost
            # key observation: only adjacent pairs matter in final sorted segment
            seg = a[l:r+1]
            if len(seg) <= 1:
                print(0)
                continue

            # In optimal sorting, the maximum swap cost equals
            # maximum product among adjacent elements in sorted version
            seg.sort()
            ans = 0
            for i in range(len(seg) - 1):
                ans = max(ans, seg[i] * seg[i+1])

            print(ans)

def main():
    solve()

if __name__ == "__main__":
    main()
```该实现直接反映了简化的核心观察：一旦我们对一个段进行排序，它就会永久排序，因此我们物理上更新数组。 对于查询，成本仅取决于该段的排序排列，因为在任何最佳相邻交换序列中，最大成本交换发生在按排序顺序的相邻元素之间。 因此，我们暂时对查询段进行排序并计算最大相邻乘积。 

关键细节是类型 1 操作永久修改数组状态，因此我们必须写回已排序的段。 忘记这一点会导致错误的答案，因为后续查询取决于更新的结构。

 ## 边缘情况

 对于由相同值组成的线段，每个相邻的乘积都是相同的，因此答案就是那个正方形。 该算法可以处理此问题，因为排序不会改变邻接关系，并且扫描相邻对会产生正确的恒定最大值。 

对于包含零的段，任何涉及零的交换都会贡献零成本。 该算法正确地包含了这些，但除非所有值都为零，否则它们永远不会占主导地位。 

对于单元素查询，不存在相邻对，因此循环不会执行，并且成本保持为零，与定义匹配，因为不需要交换。 

对于已经排序的段，算法仍然重新排序，但结构不变，相邻产品扫描直接匹配所需成本。
