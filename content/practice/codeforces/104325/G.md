 ## 解决方案
 ## 问题理解

 我们站在一个圆形排列的前面$N$门。 从任意门$x$，我们可以执行单一类型的操作：选择步长$i$并准确移动$i$位置向前，经过门时绕回$N$。 每个这样的步长都有固定成本$C_i$，并且随着步长的增加，所有成本都是单调非增加的，因此较长的跳跃永远不会比较短的跳跃更昂贵。 

我们从 1 号门开始，但仅靠移动并不能自动“解锁”所有东西。 当我们执行移动后落在门上时，门就被认为是打开的。 目标是选择一系列跳跃，以便每扇门至少被访问一次，从而最小化总成本。 

重要的结构约束是我们不会选择门之间的任意过渡。 每一步都是从一个小菜单中选择的固定长度的跳跃$N$选项，并且每次使用跳跃都会支付全部费用，无论使用的频率如何。 

输入大小达到$10^5$，它排除了任何显式模拟访问序列或尝试跳转选择的所有子集的解决方案。 任何平方项$N$已经太慢了，甚至$O(N \log N)$解决方案必须仔细论证，因为结构是全局的而不是局部的。 

当人们假设我们只需要选择一个最佳跳跃大小并重复它时，就会出现天真的思维的微妙失败案例。 例如，有成本$[5, 4, 3, 2]$，仅重复选择第 4 步似乎很有吸引力，但如果步长与$N$。 另一个误导性的情况是，贪婪总是选择最便宜的可用步骤似乎是最佳的，但重复的小步骤可能会使我们陷入总使用次数较高的冗余循环中。 

真正的困难在于覆盖范围取决于模块化结构，而不仅仅是成本订购。 

## 方法

 暴力的想法会尝试模拟所有可能的跳跃序列并跟踪访问的位置。 从每个状态（当前位置和访问过的掩码），我们可以尝试所有步长。 这立即变成指数，因为访问集有大小$2^N$，甚至忽略位掩码，路径数量也会由于循环而爆炸性增长。 

一个稍微不那么幼稚的尝试是考虑选择步长的子集并决定如何使用它们来覆盖所有模余数$N$。 但即便如此，检查所选集合是否生成整个循环也需要对 gcd 结构和步骤组合进行推理，这表明问题本质上是数论问题，而不是组合搜索问题。 

关键的见解来自于反转视角：不要考虑圆上的路径，而要考虑所选步长会创建多少个不同的“组件”。 步长$i$将圆分成$\gcd(N, i)$不相交的循环。 如果我们使用步骤$i$，我们只在这些周期内进行探索。 为了最终访问所有内容，我们需要足够的步骤，以便随着时间的推移，组合效果将所有这些循环合并为单个连接的遍历。 

由于成本随着步长的大小而单调递减，因此就成本而言，较大的步长总是至少与较小的步长一样好。 这表明我们希望尽可能依赖大步长，但大步长可能连接性较差（大 gcd）。 较小的步骤可以改善连接性，但成本较高。 

问题变成选择多组步长，其 gcd 效应最终变为 1，确保完全连接，同时最小化总成本。 

这正是一个经典的“将 gcd 构建为 1”结构，其中每个步长都有助于当前状态的除数减少。 最优策略可以表述为 DP over gcd 状态：我们跟踪实现迄今为止使用的步骤集的某个 gcd 的最佳成本。 

包含步长的成本$i$是$C_i$，我们从当前的 gcd 状态过渡$g$到$\gcd(g, i)$。 我们希望以最小的成本以 gcd 1 结束。 

因为$N$取决于$10^5$，我们可以将 gcd 状态视为高达$N$，并且可以使用标准除数分组来优化转换。

 | ---| ---| ---| ---|
 | 路径上的暴力破解 | 指数| 指数| 太慢了 |
 | DP 超过 gcd 状态 |$O(N \log N)$|$O(N)$| 已接受 |

 ## 算法演练

 1.我们解读每个步长$i$作为一项可以减少当前“连接状态”的操作$g$到$\gcd(g, i)$。 最初，在选择任何步骤之前，状态是$N$，因为我们正在有效地考虑所有位置模$N$。 
2.我们定义一个DP数组，其中`dp[g]`是达到所选步长的当前 gcd 等于的状态所需的最小成本$g$。 我们初始化`dp[N] = 0`因为尚未选择任何操作。 
3. 我们迭代步长从 1 到$N$。 对于每个步长$i$，我们考虑它的成本$C_i$，并且我们尝试将其应用到所有现有的 GCD 状态。 
4. 对于每个当前的gcd状态$g$，我们计算下一个状态$ng = \gcd(g, i)$。 我们尝试放松`dp[ng]`和`dp[g] + C_i`。 这代表添加步骤$i$到我们选择的集合。 
5. 我们以步长递增的顺序处理状态或维护 DP 的临时副本，以便在同一迭代中不会重用转换，确保每个步骤仅计算一次。 
6. 处理完所有步长后，答案为`dp[1]`，因为 gcd 1 对应于所有残基均可到达的全连接结构。 

这样做的原因是 gcd 进化完全捕获了模块化循环上步长引起的连接性。 任何步骤序列都定义了一个子组$\mathbb{Z}_N$，并且该子组的大小完全由所选步长的 gcd 决定，并且$N$。 达到gcd 1相当于生成全循环组，这意味着每个门都是可达的。 由于在 DP 状态下每个步骤最多选择一次，因此我们有效地选择了生成完整组的总成本最小的步长子集。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = list(map(int, input().split()))
    
    # dp[g] = min cost to achieve gcd-state g
    INF = 10**18
    dp = [INF] * (n + 1)
    dp[n] = 0

    for i in range(1, n + 1):
        cost = c[i - 1]
        new_dp = dp[:]  # do not reuse updated states in same iteration
        
        for g in range(1, n + 1):
            if dp[g] == INF:
                continue
            ng = gcd(g, i)
            if dp[g] + cost < new_dp[ng]:
                new_dp[ng] = dp[g] + cost
        
        dp = new_dp

    print(dp[1])

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

if __name__ == "__main__":
    solve()
```此实现在可能的 gcd 状态上维护完整的 DP，并使用每个步长恰好更新它们一次。 临时数组确保我们不会在单次迭代中多次链式应用同一步骤，这会错误地模拟无限重用。 

gcd 函数是手动实现的，以避免开销并将解决方案保持在严格的限制范围内。

 ## 边缘情况

 一个关键的边缘情况是当$N = 1$。 唯一的举措是第 1 步，答案很简单$C_1$，因为没有超出单个节点的移动概念。 

另一个边缘情况是当$C_N$与其他相比非常小。 在这种情况下，选择步骤$N$立即将所有转换折叠成一个循环，使 gcd 等于$N$，则不可能进一步减少。 该算法正确处理了这个问题，因为 dp 从$N$直接到$\gcd(N, N) = N$，它不会改变状态，从而防止错误的过度计数。 

第三种情况是所有成本均等的情况。 然后，解决方案倾向于选择能够快速降低 gcd 的最小步骤集，并且 DP 确保任何冗余步骤都不会改善答案，因为它只会增加成本，而不会改善状态。
