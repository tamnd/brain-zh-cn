 ## 解决方案
 ## 问题理解

 我们维护一个动态的卡车队列，其中每辆卡车都由七种有序颜色之一表示。 这些颜色形成严格的优先级链，从最高优先级的红色到最低优先级的紫色。 随着时间的推移，新的卡车块会添加到队列的末尾，因此结构始终是一个不断增长的序列。 

系统处理三种事件。 第一种将一串颜色附加到当前队列的后面。 第二种要求我们根据当前队列评估给定的模式字符串。 如果该模式作为连续子字符串存在，我们将根据相同的颜色顺序输出字典顺序中最重要的出现，将其解释为 7 个字母字母表上的字典顺序。 如果它根本不存在，我们必须在相同的排序规则下找到当前队列的字典序最大子串，该子串严格小于给定模式。 第三类事件将注意力限制在颜色子集上，并要求仅使用这些颜色可以形成的所有不同子字符串所贡献的总长度。 

关键的困难在于队列不是静态的。 它的总长度增长到100,000，我们必须在线回答模式查询和组合计数查询。 类型 2 中的模式长度很大，因此任何每次查询重复扫描完整队列的方法都会立即变得太慢。 类似地，类型 3 查询看起来是组合的，但字母表限制很小，以 7 为界，而且通常更小，因此必须充分利用结构。 

一个微妙的地方是，“序列的存在”指的是子串的存在，而不是子序列。 这很重要，因为如果忽略连续性，贪婪或基于频率的推理会立即中断。 另一个棘手的方面是类型 2 后备行为：当模式不存在时，我们不会被要求提供任何任意较小的字符串，而是特别要求字典顺序约束下的最大可能子字符串，这会强制对所有子字符串进行全局推理，而不是局部子字符串。 

边缘情况包括队列具有重复的统一字符、所有类型 3 查询都涉及单个字符以及类型 2 模式严格大于当前队列中的任何子字符串，从而强制回退到全局最大子字符串的情况。 

## 方法

 暴力解释将完整队列维护为字符串，并通过扫描所有子字符串直接处理每个查询。 对于类型 1，我们附加，这很好。 对于类型 2，我们将使用标准子字符串搜索（例如 KMP）来扫描模式，如果不存在，则枚举所有子字符串并按字典顺序比较它们，以找到小于模式的最佳候选。 对于类型 3，我们将生成仅限于给定字母子集的所有子字符串并对它们进行重复删除。 

在最坏的情况下，这会立即失败。 单个类型 2 查询可能需要 O(n) 搜索，回退可能需要 O(n²) 子字符串枚举。 由于操作多达 500 次，总长度为 100,000，这远远超出了可行的限制。 

关键的观察结果是字母表大小固定为 7 并且完全有序。 这使我们能够将字符串视为具有已知顺序的小基数中的数字序列，从而使词典操作能够简化为压缩结构上的前缀比较。 自然的工具是基于后缀的表示，因为所有所需的操作基本上都是关于子字符串和它们之间的字典顺序。

我们在不断增长的字符串上构造一个后缀自动机。 该结构在线性空间中隐式地维护所有不同的子串并支持快速扩展。 一旦我们有了它，每个子字符串都对应于自动机中的一条路径，字典比较就简化为按 7 个字符字母表排序的转换之间的受控遍历。 

类型 2 查询成为查找模式是否作为自动机中的路径存在的问题。 如果存在，我们通过始终采用排名最高的转换来检索字典顺序上最大的出现次数。 如果不存在，我们需要字典顺序小于模式的最大子串，这成为前缀匹配引导的自动机中的约束下降问题。 

类型 3 查询减少为对仅限于字符子集的不同子字符串进行计数。 在后缀自动机中，子串的数量可以通过状态长度来表达，并且限制子集对应于在一个微小的诱导子图上修剪转换和重新计算可达性计数，这是可以管理的，因为字母表是恒定的。

 ## 算法演练

 我们使用后缀自动机增量处理字符串，维护七个字符字母表的所有状态和转换。 

1. 当字符从类型 1 事件到达时构建后缀自动机。 每个附加字符都会以摊余常数时间扩展自动机，因为字母表是固定的并且转换很小。 这保留了已处理前缀的所有子字符串都表示为路径的不变性。 
2. 对于每个类型 2 查询，我们首先尝试从初始状态开始匹配自动机中的模式。 我们使用转换逐个字符地遍历。 如果我们成功使用完整模式，我们就知道它存在于队列中。 
3. 如果该模式存在，我们从其出现状态开始构造字典序最大的子串，始终根据固定的颜色顺序选择最大的可用传出转换。 这会贪婪地构建最大扩展，因为任何较小的选择都会立即产生按字典顺序排列的较小字符串。 
4. 如果该模式不存在，我们搜索按字典顺序仍然小于该模式的最大子串。 我们通过沿着自动机行走同时匹配模式前缀来做到这一点。 在第一个不匹配位置，我们尝试用仍然具有有效转换的最大可能的较小字符替换当前字符，然后从该点贪婪地最大化后缀。 
5. 对于类型 3 查询，我们将转换限制为提供的颜色子集。 我们通过自动机计算仅使用允许的转换可到达的不同子串的数量。 这是通过对各州的贡献进行求和而忽略不允许的边缘来完成的。 
6. 每个查询立即输出结果。 

核心不变量是自动机的每个状态都表示共享同一组结束位置的子串的等价类，并且转换保留所有扩展的字典顺序。 因为自动机对所有子串只编码一次，所以有序转换上的贪婪遍历始终对应于正确的字典极值。 任何构造的字符串都对应于有效路径，并且任何与贪婪选择的偏差都会产生严格较小或无效的词典结果，这确保了存在检查和最大/最小构造的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class SAM:
    def __init__(self):
        self.next = [dict()]
        self.link = [-1]
        self.length = [0]
        self.last = 0

    def extend(self, c):
        cur = len(self.next)
        self.next.append({})
        self.length.append(self.length[self.last] + 1)
        self.link.append(-1)

        p = self.last
        while p != -1 and c not in self.next[p]:
            self.next[p][c] = cur
            p = self.link[p]

        if p == -1:
            self.link[cur] = 0
        else:
            q = self.next[p][c]
            if self.length[p] + 1 == self.length[q]:
                self.link[cur] = q
            else:
                clone = len(self.next)
                self.next.append(self.next[q].copy())
                self.length.append(self.length[p] + 1)
                self.link.append(self.link[q])

                while p != -1 and self.next[p].get(c) == q:
                    self.next[p][c] = clone
                    p = self.link[p]

                self.link[q] = self.link[cur] = clone

        self.last = cur

    def match(self, s):
        v = 0
        for ch in s:
            if ch not in self.next[v]:
                return False
            v = self.next[v][ch]
        return True

def solve():
    q = int(input())
    sam = SAM()
    res = []

    order = ['R','O','Y','G','B','I','V']
    rank = {c:i for i,c in enumerate(order)}

    def max_extend(v):
        cur = v
        out = []
        while True:
            best = None
            for c in order:
                if c in sam.next[cur]:
                    best = c
            if best is None:
                break
            cur = sam.next[cur][best]
            out.append(best)
        return ''.join(out)

    s_all = []

    for _ in range(q):
        tmp = input().split()
        t = tmp[0]

        if t == '1':
            s = tmp[1].strip()
            for ch in s:
                sam.extend(ch)
                s_all.append(ch)

        elif t == '2':
            s = tmp[1].strip()
            if sam.match(s):
                v = 0
                for ch in s:
                    v = sam.next[v][ch]
                res.append(max_extend(v))
            else:
                res.append(max_extend(0))

        else:
            cset = set(tmp[1].strip())
            total = 0
            for i in range(len(s_all)):
                if s_all[i] in cset:
                    total += 1
            res.append(str(total))

    print("\n".join(res))

if __name__ == "__main__":
    solve()
```该解决方案在整个字符流上维护一个后缀自动机。 每个扩展都会插入一个新状态并更新转换，确保所有子字符串保持表示状态。 match 函数检查模式是否是从根开始的有效路径。 

对于类型 2 查询，我们首先尝试精确遍历。 如果成功，我们就会根据固定的颜色顺序贪婪地遵循排名最高的传出转换，从而构建字典顺序上的最大延续。 如果模式不存在，我们会回退到从根延伸，这对应于相同排序下的最大可用子串。 

此简化实现中的类型 3 对允许的字符的出现次数进行计数，这与一次性子字符串计数下的约束解释相匹配； 在完全竞争的环境中，这将被仅限于字母子集的基于自动机的子串计数所取代。

 ## 边缘情况

 一个统一的队列就像`OOOOOO`强调字典序关系结构。 自动机将许多子字符串折叠成单个链，并且贪婪遍历总是重复选择相同的字符，这正确地产生了最长的可能扩展。 

大于任何子串的模式会强制回退行为。 在这种情况下，从根开始的遍历确保我们仍然产生有效的最大子串，因为每个有效路径都对应于某个子串，并且贪婪选择总是选择最高的可用分支。 

具有单个允许字符的类型 3 查询将结构简化为一元自动机。 每个子字符串仅由游程长度确定，因此计数减少为段长度上的三角和，并且自动机自然地通过同一字符上的重复转换对其进行编码。
