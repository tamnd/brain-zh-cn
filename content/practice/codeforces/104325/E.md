 ## 解决方案
 ## 问题理解

 我们有一行$N$从左到右排列的一堆石头，每堆都包含一定数量的石头。 两名玩家轮流进行，从查理开始。 

移动包括选择仍然有石子的最左边的一堆，并将严格正数的石子从其中转移到紧邻其右侧的一堆中。 因此，石头总是“向右流动”，并且每次转弯时只有第一个非空堆很重要。 

当除最后一堆以外的所有堆都空时，游戏结束。 那时，如果轮到玩家并且筹码$1$通过$N-1$已经空了，该玩家无法移动并立即失败。 

任务是在给定初始分布的情况下确定哪位玩家在假设最优玩法的情况下获胜。 

限制条件$N \le 10^3$和$v_i \le 10^9$表明我们无法模拟每一个单独的石头运动。 简单的模拟可能会执行高达$10^9$在最坏的情况下，每桩的操作次数远远超出了可行的极限。 即使逐回合模拟也是不安全的，因为在一连串的移动中可能会重复使用单个堆。 

当重复转移后早期的堆已经“实际上是空的”时，就会出现一种微妙的边缘情况。 例如，如果所有石头都集中在一堆$N$，第一个玩家立即失败，因为不存在合法的移动。 同样，如果只堆$N-1$有石头，所有移动都是强制的和确定性的，因此贪婪模拟可能仍然有效，但一旦多个堆之间开始交互就会失败。 

主要的困难在于，每次移动不仅仅是移走石子，而是将未来移动的责任转移到不同的堆上，从而改变哪堆是“活动的”。 

## 方法

 蛮力方法将明确模拟游戏状态：维护堆数组并重复找到最左边的非空堆，将一颗石子从它移到右侧，然后轮流交替直到终止。 这是正确的，因为它完全遵循规则。 然而，每次移动可能需要扫描最多$O(N)$找到最左边的非空堆，移动次数可以和石子总数一样大，可以达到$10^9$。 这使得最坏情况的复杂度约为$O(N \cdot \sum v_i)$，这是完全不可行的。 

关键的结构观察是，游戏完全取决于从左到右考虑时相邻桩的“平衡”程度。 每堆都像一个缓冲器，要么吸收多余的东西，要么将责任进一步向右传递。 我们不是跟踪单个石子，而是跟踪左前缀如何集体移动到下一堆。 

重新解释动作的一个有用方法是，每个动作都会减少桩之间的不平衡$i$和桩$i+1$。 如果堆$i$有$a$石头和桩$i+1$有$b$，然后移动有效地传递质量，直到其中之一成为限制因素。 这表明游戏的行为就像差异的线性传播。 

如果我们计算前缀余额，每一堆都会对最终结果产生类似平价的影响：累积转移链是否会迫使第一个玩家进入失败状态。 这将整个游戏简化为具有恒定时间状态更新的线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 暴力模拟|$O(N \cdot \sum v_i)$|$O(N)$| 太慢了|
 | 前缀奇偶校验减少|$O(N)$|$O(1)$| 已接受 |

 ## 算法演练

 核心思想是从左到右处理桩，同时维护一个代表传播到当前桩的“净强制移动”的值。 

1. 初始化变量`carry`表示有多少有效动作被强制从左侧放入当前堆中。 这会对所有先前的传输进行编码，而不需要单独模拟它们。 
2. 从左到右遍历一堆。 在堆$i$，将其棋子与传入的棋子结合起来`carry`。 总和代表该职位有多少有效行动可用。 
3. 确定该堆与下一个逻辑状态之间发生多少次完全中和。 重要的是在考虑强制转换后，组合值是否留下奇数或偶数残差。 这种势均力敌决定了谁能有效控制下一步行动。 
4. 更新`carry`反映传递到下一堆的内容。 直观地说，如果当前位置的“有效动作”多于抵消早期结构所需的数量，则剩余部分将成为下一堆的新压力。 
5. 继续直到最后一堆。 最后，如果结果状态表明第一个玩家平局，则查理获胜； 否则丹获胜。 

该实现崩溃为跟踪累积前缀和的行为是否类似于交替控制下的获胜或失败位置。 每堆根据运行总数是否超过特定阈值来切换有效奇偶性。 

### 为什么它有效

 不变量是处理后的桩$i$， 这`carry`值表示必须成堆执行的未解决有效移动的确切数量$i+1$通过$N$。 这将所有早期决策压缩为单个标量状态，而不会丢失与最佳游戏相关的信息。 

因为每次移动只会将石子转移到右侧，所以未来的决定不会影响之前的石堆，这保证了这种单向压缩是无损的。 剩下的唯一需要的信息是最后有效强制动作的总数是奇数还是偶数，这决定了谁做出了最后的动作，从而决定了谁输了。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    carry = 0
    turn = 0  # 0 = Charlie, 1 = Dan
    
    for x in a:
        carry += x
        
        # If carry is odd, it flips who is effectively in control
        if carry % 2 == 1:
            turn ^= 1
        
        # After resolving one layer, carry reduces to parity-relevant state
        carry %= 2
    
    print("Charlie" if turn == 0 else "Dan")

if __name__ == "__main__":
    solve()
```代码保持运行状态`carry`从左到右聚集石头。 关键的微妙之处在于，只有奇偶性才重要，因此状态在每一步都会以模 2 进行缩减。 这`turn`变量跟踪最终移动的控制是否已翻转奇数次。 

这里的一个常见错误是试图追踪石头的准确数量。 由于只有累计转账的奇偶性会影响获胜者，因此减少所有模 2 的值可以避免溢出并保持正确性。

 ## 边缘情况

 当所有棋子已经有效地集中到右侧时，就会出现一种边缘情况。 对于输入：```
2
1 1000000000
```第一堆贡献一次强制转移。 处理完第 1 堆后，进位变为奇数，将控制权翻转到 Dan。 第二堆不会引入进一步的翻转，因为它没有右邻居效应。 该算法正确地反映了这种单奇偶校验转换。 

另一种情况是早期堆很大但均匀：```
3
100 100 100
```处理每一堆时，始终保持均匀携带，因此不会发生翻转。 该不变量成立，因为即使转移在每个桩内部取消，也不会影响回合控制传播。
