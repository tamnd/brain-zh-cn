 ## 解决方案
 ## 问题理解

 我们有`n`食物类型。 类型`i`有`k_i`份，如果我们决定保留这种类型，那么每一份都必须在一天结束时吃完`t_i`。 探险队每天正好可以消耗`c`只要有足够的食物就分份。 任务不是最大化吃的份数。 就是选择尽可能多的食物类型，以便在变质之前完全吃完。 输出是该集合的大小和所选类型的索引。 

这些限制迫使我们放弃尝试子集。 和`n`最多`200000`，检查许多组合的方法是不可能的，因为即使是二次解也已经接近数百亿次运算。 的大值`k_i`,`t_i`， 和`c`也意味着我们无法模拟日子。 该解决方案必须根据截止日期推断总容量并大致运行`O(n log n)`时间。 

导致错误的主要情况与截止日期解释以及大产品可能阻碍许多小产品的事实有关。 例如：```
1 2
1 2
```正确的输出是：```
1
1
```因为是两个人，所以第一天可以吃两份。 将截止日期视为一天的开始的解决方案`t_i`而不是一天的结束`t_i`会错误地拒绝该产品。 

另一个例子是：```
2 1
1 5
5 4
```正确的输出是：```
1
2
```仅第一个产品第一天就需要五份，这是不可能的。 第二个产品可以在五天内完成。 始终保留最早的产品而不删除任何内容的贪婪解决方案将会失败，因为不可能的早期产品会消耗可用容量。 

最后一个极端情况是产品正好填满剩余容量：```
2 3
2 6
3 3
```正确的输出是：```
2
1 2
```两天后可以吃六份，三天后可以吃九份。 平等案件必须被接受。 

## 方法

 直接的解决方案是尝试每一种可能的食物类型，并检查该组是否可以安排。 对于选定的集合，按截止日期对产品进行排序并检查每个前缀将告诉我们每天到期的总金额是否符合要求`c * day`可用进食能力的部分。 这种方法是正确的，因为当每个截止日期前缀都有足够的总容量时，截止日期时间表是可行的。 然而，检查所有子集需要`2^n`选择，这已经是不可能的事`n`50左右，更不用说`200000`。 

看待问题的一个更有用的方法是从所有产品开始，只删除那些妨碍可行性的产品。 按腐败天数的增加对产品进行分类。 处理此订单时，每个前缀包含截止日期最多为当前截止日期的所有产品。 如果当前前缀需要太多部分，则必须丢弃该前缀中的某些产品。 

重要的观察是，当前缀不可能时，删除部分数量最多的产品始终是最好的修复。 前缀中的所有产品都已通过相同的截止日期检查，因此删除任何一种产品都会导致所选类型数量的相同减少。 移除最大的一个，为未来的产品留下最多的剩余产能。 这与用于最大化已完成作业数量的经典调度贪婪算法背后的交换参数相同。 

按截止日期排序后，我们维护所选产品及其总份数。 当添加产品破坏可行性时，我们会删除最大的选定产品`k_i`。 堆有效地支持这种删除。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 |`O(2^n * n)`|`O(n)`| 太慢了|
 | 最佳|`O(n log n)`|`O(n)`| 已接受 |

 ## 算法演练

 1. 对所有产品按升序排序`t_i`。 必须首先考虑变质日期较早的产品，因为每个产品都有截止日期`d`竞争第一个期间的可用总容量`d`天。 
2. 将当前产品添加到所选集合中。 增加所选产品的部分总数并将产品插入到按以下顺序排序的最大堆中`k_i`。 
3. 检查所选产品是否仍能在当前期限内完成。 条件是：$$\text{total portions} \leq c \times t_i$$如果此条件失败，则当前组包含太多必须在这一天吃完的部分。 

1. 取出最大的产品`k_i`从堆中取出它的大小并从总数中减去它的大小。 这保留了最大可能数量的产品类型，因为一种删除的类型总是可以修复违规行为，并且删除最大的类型会浪费最少数量的可能的未来选择。 
2.处理完所有产品后，剩余的堆包含最大可能的完全可消耗产品集的索引。 

工作原理：处理完截止日期到某一天的所有产品后，维护的集合是满足当天容量限制的产品中最大的可能集合。 如果添加产品会使集合无效，则每个有效的解决方案都必须从此前缀中删除至少一个产品。 移除最大的产品可以在仅移除一种类型的同时将消耗容量的损失降至最低。 这使集合对于当前前缀保持最佳状态，并且在处理以后的截止日期时，不变式继续保持不变。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, c = map(int, input().split())
    products = []

    for i in range(1, n + 1):
        t, k = map(int, input().split())
        products.append((t, k, i))

    products.sort()

    heap = []
    total = 0

    for t, k, idx in products:
        total += k
        heapq.heappush(heap, (-k, idx))

        if total > c * t:
            removed_k, _ = heapq.heappop(heap)
            total += removed_k

    ans = [idx for _, idx in heap]

    print(len(ans))
    if ans:
        print(*ans)

if __name__ == "__main__":
    solve()
```产品按截止日期排序，以便每张检查都代表必须在当天完成的所有产品。 堆存储负大小，因为 Python 提供了最小堆，对值求负会将其变成最大堆。 

变量`total`存储当前接受的产品中的份数总数。 当它超过`c * t`，当前集合无法在当前截止日期之前完成。 删除堆最大值就足够了，因为只需丢弃一个产品即可恢复不变量。 

Python 整数可以安全地处理大值。 各部分的最大可能总和远大于 64 位整数，因此具有固定宽度整数的语言需要更宽的类型。 乘法`c * t`还必须在没有溢出的情况下进行评估。 

输出顺序并不重要，因此可以直接打印堆内容。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(n log n)`| 排序需要`O(n log n)`，以及每次堆插入或删除成本`O(log n)`|
 | 空间|`O(n)`| 排序后的产品列表和堆存储最多所有产品|

 该算法仅执行排序和堆操作`200000`产品，完全符合典型的竞争性编程限制。 不会执行数天的模拟，因此大的截止时间值不会影响运行时间。

 ## 边缘情况

 对于第一个截止日期解释案例：```
1 2
1 2
```该算法对唯一的产品进行排序，将其两部分相加，然后进行检查`c * t = 2 * 1 = 2`。 由于总数等于可用容量，因此满足条件。 产品保持选中状态，给出输出：```
1
1
```对于必须移除大型产品的情况：```
2 1
1 5
5 4
```第一个产品添加总计`5`，但第一天的容量仅为`1`。 堆立即删除该产品。 然后添加第二个产品，其四部分适合五天内的可用时间。 最终输出仅包含类型 2。 

对于精确的边界情况：```
2 3
2 6
3 3
```第一个产品给出总计`6`和容量`6`，所以它仍然存在。 第二个产品将总数增加到`9`，而第三天的容量也是`9`。 由于相等有效，因此不会发生任何删除，并且两个产品都会被退回。
