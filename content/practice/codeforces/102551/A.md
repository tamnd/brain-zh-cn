 ## 问题理解

 任务是将三个矩形工件放置在矩形驳船上。 每个工件都有固定的边长，但每个工件都可以旋转 90 度。 文物在驳船内不得重叠，且其侧面必须与驳船侧面保持平行。 目标是找到驳船上可以容纳所有三件文物的最小可能区域。 

输入由三个工件中每一个的宽度和高度组成。 输出是选择合适的旋转和位置后可以包含它们的矩形的最小面积。 

仅涉及三个矩形，因此解决方案不受对象数量的限制。 重要的约束是边长限制，可以达到大约$10^4$。 尝试网格上矩形的每个可能位置将需要数十亿次检查，而且是不可能的。 有用的观察是，对于三个矩形，可能的相对布局的数量非常小。 我们只需要列举有意义的几何排列即可。 

一个常见的错误是只检查矩形的一个方向。 例如，一个有边的矩形$2 \times 10$另一个有边$5 \times 5$可能需要旋转第一个以实现最佳包装。 

另一种边缘情况是所有矩形都适合简单的行，但不能适合更复杂的排列。 例如：```
1 2
3 4
5 6
```最好的放置方式可能只是将所有三个垂直放置，从而提供宽度$5$和身高$6$，与面积$30$。 仅检查水平放置的解决方案会错过它。 

第二种边缘情况是最佳答案来自于将一个矩形与其他两个矩形分开：```
4 10
3 6
3 4
```第一个矩形可以位于其他两个矩形之上。 生成的矩形的宽度$6$和身高$14$,给定面积$84$。 仅检查将所有三个排成一行的解决方案将产生更大的答案。 

## 方法

 直接暴力的想法是在足够大的边界框内尝试每个矩形的所有可能位置。 由于坐标可能与输入尺寸一样大，因此这种方法很快就变得不可行。 即使只有三个矩形，扫描每个矩形的可能坐标也会创建一个与其可能位置的乘积成正比的搜索空间。 

关键的观察结果是，三个轴对齐的矩形在最佳包装中只有几种可能的关系。 一个矩形要么与另一个矩形共享一条边，要么这些矩形形成一行或一列。 任何不必要的空白都可以被删除，并使包含的矩形更小，因此最佳解决方案始终属于这些紧凑布局之一。 

该解决方案枚举了三个工件的所有旋转和所有顺序。 对于每个固定方向和顺序，它检查将矩形划分为行和列的可能方式。 由于只有$3! \times 2^3$方向和顺序选择，这种详尽的搜索是恒定的时间。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(S^6) | O(S^6) | O(1) | O(1) | 太慢了 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 已接受 |

 ## 算法演练

 1. 读取三个矩形并生成每个矩形的所有可能的旋转。 
2. 对于每种旋转组合，尝试三个矩形的每种顺序。 这样就无需猜测哪个工件在布局中占据哪个角色。 
3. 对于当前的三个定向矩形，计算所有可能的边界矩形。 检查的图案是一行三个矩形，一列三个矩形，以及每个矩形与其他两个矩形分开的情况。 
4. 用所有生成的边界矩形中最小的面积更新答案。 

这涵盖了每个最佳放置的原因是，只要三个矩形，任何紧凑的包装都可以通过垂直或水平线分成更小的组。 这些组包含一个矩形或两个矩形，这正是所列举的情况。 

为什么有效：该算法考虑了三个矩形的每一种可能的旋转和每一种可能的结构排列。 由于每个最佳包装必须属于这些结构模式之一，因此枚举找到的最小面积恰好是最小可能的驳船面积。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

from itertools import permutations, product

def solve():
    rects = []
    for _ in range(3):
        a, b = map(int, input().split())
        rects.append((a, b))

    ans = 10**30

    def add(w, h):
        nonlocal ans
        ans = min(ans, w * h)

    for order in permutations(range(3)):
        for rotations in product([0, 1], repeat=3):
            r = []
            for idx, rot in zip(order, rotations):
                a, b = rects[idx]
                if rot:
                    a, b = b, a
                r.append((a, b))

            a, b = r[0]
            c, d = r[1]
            e, f = r[2]

            add(a + c + e, max(b, d, f))
            add(max(a, c, e), b + d + f)

            add(max(a, c + e), b + max(d, f))
            add(max(a, c, e), b + d + f)

            add(max(a, c + e), b + max(d, f))
            add(max(a + c, e), max(b, d) + f)

            add(max(a + e, c), max(b, f) + d)
            add(max(a + c, e), max(b, d) + f)

    print(ans)

if __name__ == "__main__":
    solve()
```该代码首先存储三个工件。 嵌套枚举很小，因为只有六种可能的顺序和八种可能的旋转选择。 

对于每个生成的配置，代码都会计算候选边界矩形。 前两个公式对应于完整的行或列。 其余公式表示将一个矩形放置在由其他两个矩形组成的一组上。 

所有计算都使用Python整数，因此不存在溢出风险。 答案从一个非常大的值开始，每当找到较小的有效区域时就会被替换。 

主要的实现细节是旋转是显式生成的，而不是尝试在几何公式内处理它们。 这使得布局检查变得简单，并避免由于方向变化而导致丢失案例。

 ## 边缘情况

 当每个矩形都是正方形时，旋转不会改变任何东西。 例如：```
1 1
1 1
1 1
```该算法仍然枚举旋转，但每个生成的状态都是等效的。 它正确地找到了一个$1 \times 3$与区域的放置`3`。 

当细长矩形需要​​旋转时，忽略旋转会给出错误的答案。 为了：```
1 10
1 10
10 10
```将前两个矩形垂直放置在正方形旁边给出$20 \times 10$有面积的矩形`200`。 枚举包括该方向并且不会被原始输入方向捕获。 

当最佳放置不是简单的行或列时，拆分案例可以处理它。 为了：```
4 10
5 11
12 3
```该算法可以将一个工件与其他两个工件相对放置并获得面积`144`，而仅行解决方案会错过这个较小的矩形。
