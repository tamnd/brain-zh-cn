 ## 解决方案
 ## 问题理解

 我们收到一束花，其中必须准确包含`n`花，还有`m`花的种类。 每种类型都可以使用任意次数。 

每朵花的奖励模型并不是恒定的。 如果我们采取`x`花的类型`i`, 第一个贡献`a_i`，接下来的每一个都贡献`b_i`。 所以该类型的总贡献变为`a_i + (x - 1) * b_i`什么时候`x > 0`， 和`0`什么时候`x = 0`。 

任务是分配总数`n`不同类型的花朵以最大化贡献的总和。 

关键的困难在于，类型的边际值在第一次选择后会发生变化。 一种类型的第一朵花可能与后续的花显着不同，因此仅基于`b_i`或仅在`a_i`失败。 

限制条件很大：`n`可以达到`10^9`， 尽管`m`取决于`100000`。 这立即排除了任何模拟一朵一朵摘花或维持每朵花决策的方法。 任何正确的解决方案都必须将问题简化为 O(m) 或 O(m log m) 预处理。 

当类型具有非常大的值时，就会出现幼稚推理的微妙失败情况。`a_i`但很小`b_i`，反之亦然。 例如，如果一种类型有`(a, b) = (100, 1)`另一个有`(1, 100)`，仅基于第一或第二收益的贪婪选择很容易产生误导，因为第一个选择与分配的剩余结构相互作用。 

## 方法

 蛮力的想法很简单。 我们决定多少朵花`x_i`从每种类型中获取并直接计算总贡献，尝试所有有效的分布。 这是正确的，因为它评估精确的公式，但分布的数量是天文数字。 即使我们限制每个`x_i`在`n`，整数分区的数量`n`进入`m`零件远远超出了可行的计算范围。 这会立即失败，当`n`超过几十个。 

奖励函数的结构在第一个元素之后是线性的。 每种类型的行为就像一个序列：一个特殊值`a_i`，然后是无限的流`b_i`。 这表明将问题转化为选择边际贡献。 

对于每种类型，直接边际视图都会产生无限序列的收益：`a_i, b_i, b_i, b_i, ...`。 任务变成选择最好的`n`所有这些序列的值。 问题是每个序列都是无限的，因此我们无法显式枚举候选序列。 

关键的观察是，只有最好的`b_i`对于所有“非第一”选择来说，这在全球范围内都很重要。 一旦我们拿走了许多花，每增加一朵花就只贡献其类型的`b_i`，所以我们希望这些贡献尽可能大。 这表明在任何最佳解决方案中，几乎所有非首选都应该来自具有最大`b_i`，因为使用任何更小的`b_i`减少总数。 

这会破坏结构：而不是分配所有`n`任意项目，我们以最大程度对待一种主导类型`b_i`作为基础填料，我们只考虑用其他类型的优先选择“替换”其中一些基础选择是否有益。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 对所有发行版进行暴力破解 | 指数| O(1) | O(1) | 太慢了 |
 | 每次选秀的边际模拟| O(n log m) | O(n log m) | O(米) | 太慢了 |
 | 使用 max 进行最佳减少`b_i`基线 | O(米) | O(1) | O(1) | 已接受 |

 ## 算法演练

 我们将一切都简化为与最佳“默认”类型进行比较。 

### 步骤

 1. 找出所有值中的最大值`b_i`，称之为`B`。 

这代表了第一朵花之后每朵花的最佳可能价值。 
2. 从基线解决方案开始，其中所有`n`鲜花被认为来自具有价值的类型`B`。 

这给出了基本贡献`n * B`。 
3. 对于每种类型`i`，计算至少使用一次而不是仅使用基线类型的效果。 

如果我们引入类型`i`，我们从中取出一朵花，这有助于`a_i`而不是`B`。 这改变了总数`a_i - B`。 
4. 如果`a_i - B > 0`，至少包含一次此类型是有益的。 将此值添加到答案中。 
5. 将第 4 步中的所有积极贡献相加，并将其添加到基线中`n * B`。 

### 为什么它有效

 关键的不变量是，除了第一朵花之外的每一朵花在其类型内的行为都是相同的，并且这些位置的类型之间的唯一全局区别是`b_i`。 因此，所有非特殊职位的最佳分配始终是最大`b_i`。 

一旦这条基线被固定，任何偏离它的情况都只能通过首先选择类型来发生。 每个这样的偏差都会取代一个基线项目`B`第一个项目的价值`a_i`，产生增益`a_i - B`。 偏差之间不存在进一步的相互作用，因为每个被替换的位置都是独立的，并且剩余的结构仍然填充`B`。 这种独立性保证了将所有正增益相加会产生最佳配置。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    a = []
    b = []
    
    B = 0
    for _ in range(m):
        ai, bi = map(int, input().split())
        a.append(ai)
        b.append(bi)
        if bi > B:
            B = bi

    ans = n * B
    
    for i in range(m):
        gain = a[i] - B
        if gain > 0:
            ans += gain

    print(ans)

if __name__ == "__main__":
    solve()
```该解决方案首先确定最强的单位增长率`B`。 然后假设所有花都有贡献`B`，形成一个干净的基线。 通过检查其第一朵花是否比该基线更强，对每种类型进行独立评估。 如果是，我们通过用该类型的第一朵花替换一朵基线花来升级解决方案。 

一个常见的陷阱是试图模拟每种类型需要多少朵花。 这是不必要的，因为一旦基线确定，每朵额外花的贡献就已经确定。

 ## 边缘情况

 当所有的情况发生时，就会出现极端情况`b_i`是平等的。 在这种情况下，基线由所有类型共享，并且解决方案纯粹是选择具有最高值的类型。`a_i`。 该算法自然地处理这个问题，因为每个`a_i - B`是独立评估的。 

另一种情况是最好的时候`a_i`属于小类型`b_i`。 如果它的第一个值超过全局基线，算法仍然会包含它，因为无论它自己如何，替换总是有益的`b_i`。 

最后，当`n = 1`，答案很简单`max(a_i)`，因为不存在第二选择。 该公式正确减少，因为`n * B + max(a_i - B)`简化为`max(a_i)`。
