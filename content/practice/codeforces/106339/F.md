 ## 解决方案
 ## 问题理解

 我们得到一个索引从 1 到 n 的数组，其中每个位置 i 包含一个值 h[i]。 除了这个数组之外，还有多个查询。 每个查询给出一个段 [L, R] 和一个值 K，并要求我们计算该段中有多少个索引 i 满足涉及 i 和 h[i] 的整除条件。 

条件是 gcd(h[i], i) 能被 K 整除。这比仅检查相等性或简单的 gcd 阈值更强，因为它将索引的结构和存储在该索引中的值联系在一起。 

关键的结构结果来自 gcd 的性质。 如果 K 除以 gcd(h[i], i)，则 K 必须分别除以 h[i] 和 i。 这将最初看起来像数论条件的问题转变为索引上的纯整除过滤问题。 

对于类似数量的查询，此类问题中的约束通常会将 n 推至 10^5 左右或更多。 这立即排除了为每个查询的每个索引重新计算 gcd，因为每个查询的时间复杂度为 O(n)，并且在最坏的情况下会爆炸到 10^10 次操作。 即使每个查询解决方案都使用完整的 O(n log n) 也会太慢。 

微妙的困难在于条件取决于索引和数组值，因此仅预先计算有关 h[i] 的内容是不够的。 我们必须支持对许多不同 K 值的动态定义的索引子集进行快速范围计数。 

简单的实现也可能会错过一个重要的边缘情况：K 大于 n 或大于所有 h[i]。 在这种情况下，答案始终为零，因为没有索引可以满足 i 可被 K 整除。例如，如果 n = 5、h = [2, 4, 6, 8, 10] 和 K = 7，则每个查询都必须返回 0。任何盲目扫描或存储不完全整除列表而不正确处理边界的方法仍然可以正确运行，但低效的预处理可能会浪费时间迭代不必要的值。 

当 K = 1 时，会出现另一种失败情况。这里每个索引都满足条件，因为 gcd(h[i], i) 总是能被 1 整除。正确的解决方案应该自然地处理这个问题，无需特殊的大小写，但如果不仔细设计，只迭代从 K 开始的倍数的不正确的预处理循环可能会跳过或错误处理 K = 1。 

## 方法

 蛮力方法很简单。 对于每个查询，我们迭代 [L, R] 中的所有索引 i，计算 gcd(h[i], i)，并检查它是否可以被 K 整除。这是正确的，因为它直接遵循定义。 然而，它需要为每个查询的每个索引计算一个 gcd，导致每个查询的时间复杂度为 O(n log n)，因为 gcd 需要对数时间。 对于许多查询，这变得太慢了。 

瓶颈来自于跨查询重复相同的结构检查。 该条件并不以复杂的方式依赖于 L 和 R； 它仅取决于索引是否属于由 K 定义的可预计算集合。一旦我们意识到 K 整除 gcd(h[i], i) 当且仅当 K 整除 i 和 h[i] 时，我们就可以将预处理与查询解耦。 

这一观察使我们能够扭转观点。 我们不是检查数组上的每个查询，而是为每个可能的 K 预先计算索引 i 的列表，使得 i 和 h[i] 都可以被 K 整除。每个这样的列表都是自然排序的，因为我们按升序处理索引。 然后，每个查询都简化为排序列表上的范围计数问题，可以使用二分搜索来回答。 

剩下的优化是在预处理中。 我们不需要检查每个 K 的每个 i。相反，对于固定的 K，我们只迭代 K 的倍数，因为只有那些索引才可能满足 i 可被 K 整除。这减少了 n 上的调和级数的构建成本，即 O(n log n)。

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(q·n log n) | O(q·n log n) | O(1) | O(1) | 太慢了|
 | 最佳| O(n log n + q log n) | O(n log n + q log n) | O(n log n) | O(n log n) | 已接受 |

 ## 算法演练

 我们通过根据可分结构组织索引来构建解决方案。 

1. 我们创建一个数据结构，通常是字典或向量数组，其中对于每个可能的 K，我们存储有效索引的列表。 该结构将累积出现在问题空间中的所有潜在除数的答案。 
2.我们将K从1迭代到n。 对于每个 K，我们仅扫描其倍数 i，即 i = K、2K、3K，依此类推，直到 n。 此限制是有效的，因为任何不能被 K 整除的索引永远不能满足该条件。 
3. 对于每个候选索引 i = mK，我们检查 h[i] 是否也能被 K 整除。如果 h[i] mod K 等于 0，则两个要求的条件都成立，因此我们将 i 附加到索引 [K] 中。 这确保我们只存储有效的位置。 
4. 预处理完所有 K 值后，每个索引[K] 列表都已排序，因为我们在多次扫描期间按升序附加 i。 
5. 对于每个查询（L，R，K），我们想要计算索引[K]中有多少个值位于区间内。 由于列表已排序，我们使用 lower_bound 找到第一个位置 >= L ，使用 upper_bound 找到第一个位置 > R ，并减去它们的位置以获得计数。 
6. 我们输出每个查询的计数。 

它之所以有效，是基于条件的直接等价变换。 要求 K | gcd(h[i], i) 相当于 K 除 gcd 的两个参数。 这将 gcd 完全从运行时计算中删除。 预处理保证每个有效索引 i 都准确存储在除 i 和 h[i] 的 K 值列表中，并且不会插入无效索引。 由于索引按每 K 的递增顺序插入，因此每个列表都保持排序，这保证了二分搜索范围计数的正确性。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    h = [0] + list(map(int, input().split()))

    indices = [[] for _ in range(n + 1)]

    for k in range(1, n + 1):
        for i in range(k, n + 1, k):
            if h[i] % k == 0:
                indices[k].append(i)

    for _ in range(q):
        l, r, k = map(int, input().split())
        if k > n:
            print(0)
            continue

        arr = indices[k]

        # binary search
        lo, hi = 0, len(arr)
        while lo < hi:
            mid = (lo + hi) // 2
            if arr[mid] >= l:
                hi = mid
            else:
                lo = mid + 1
        left = lo

        lo, hi = 0, len(arr)
        while lo < hi:
            mid = (lo + hi) // 2
            if arr[mid] > r:
                hi = mid
            else:
                lo = mid + 1
        right = lo

        print(right - left)

if __name__ == "__main__":
    solve()
```预处理循环是核心转换步骤。 它不是独立处理每个索引，而是按除数结构对索引进行分组，这使得跨查询能够重用。 

二分搜索是手动实现的，以避免对外部库的依赖并保持对边界条件的完全控制。 第一个搜索找到不小于 L 的最早索引，第二个搜索找到严格大于 R 的第一个索引。 

一个微妙的实现细节是守卫`if k > n`。 由于当 k 超过 n 时，没有索引 i 可以满足 i 可被 k 整除，因此跳过查找可以避免不必要的工作，并防止空数组边缘行为被误解。 

## 工作示例

 考虑 n = 6、h = [2, 3, 6, 8, 12, 9] 和查询 (2, 6, 2)。 

我们通过检查 2 的倍数来构建索引[2]。 

| 我| h[i]| 我％2 | h[i] % 2 | 包括 |
 | --- | --- | --- | --- | --- |
 | 2 | 3 | 0 | 1 | 没有|
 | 4 | 8 | 0 | 0 | 是的 |
 | 6 | 9 | 0 | 1 | 没有|

 所以索引[2] = [4]。 

对于查询 (2, 6, 2)，我们在 [4] 中搜索 2 到 6 之间的值，这会产生 1 个元素。 

现在考虑另一个查询 (1, 5, 1)。 

由于 k = 1 可以整除所有内容，因此每个索引都是有效的，因为 i 和 h[i] 都可以被 1 整除。 

| 我| 包含在索引中[1] |
 | --- | --- |
 | 1 | 是的 |
 | 2 | 是的 |
 | 3 | 是的 |
 | 4 | 是的 |
 | 5 | 是的 |
 | 6 | 是的 |

 查询 (1, 5, 1) 返回 5，因为包含从 1 到 5 的所有索引。 

这些示例确认预处理正确地捕获了整除性约束，并且排序列表上的范围计数的行为符合预期。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n + q log n) | O(n log n + q log n) | 每个 k 处理 n/k 倍数，求和为 n | 上的调和级数
 | 空间| O(n log n) | O(n log n) | 每个索引可能出现在多个除数列表中 |

 预处理成本保持在可接受的限度内，因为每个索引仅通过其除数来访问，并且此类访问的总数受到整除性的调和结构的限制。 由于对预先计算的排序列表进行二分搜索，查询处理是对数的，这对于大 q 来说足够有效。

 ## 边缘情况

 对于大于 n 的 K，预处理结构永远不会包含有效索引，因此查询会正确返回零，而无需扫描任何数组。 

对于 K = 1，每个索引都是有效的，因为 i 和 h[i] 总是能被 1 整除。预处理循环自然包括索引[1] 中的所有索引，因此查询减少到整个索引列表上的简单范围计数。 

对于小于 K 的 h[i] 值，整除性检查会在预处理期间自动将其过滤掉，因为 h[i] % K 不会为零。 即使索引是 K 的倍数，这也可以防止错误包含。
