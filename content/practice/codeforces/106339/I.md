 ## 解决方案
 ## 问题理解

 我们有一条道路分成几段，每段都有一个初始雪高。 该过程反复修改这些高度。 在每一步中，我们都会找到当前仍具有雪结构的所有分段中最高的分段，并降低其高度。 缩减规则是局部的：所选段被降低以匹配其两个邻居中较大的一个，除非它已经等于该值。 重复此操作，直到不可能进一步减少，这意味着在此规则下配置变得稳定。 

任务是确定应用所有此类贪婪归约后的最终状态，或者等效地有效模拟此过程，直到其自然收敛。 

输入应理解为表示线上初始雪高的整数序列。 输出对应于过程稳定后的最终高度，此时没有任何段严格高于其局部邻域在重复缩减下所允许的高度。 

这些约束意味着段的数量很大，在该问题的 Codeforces 风格版本中通常高达 200,000 个。 重复扫描全局最大值并执行局部更新的简单模拟将在每次操作上花费线性时间，并且在最坏的情况下可能会对每个高度级别的每个元素执行一次更新，从而导致二次或更糟糕的行为。 当 n 约为 2×10^5 时，任何超出 O(n log n) 或 O(n) 的操作都是不可行的。 

当多个峰相互作用时，会出现微妙的失败情况。 例如，考虑一个像这样的数组`[1, 5, 2, 4, 1]`。 总是选择第一个最大值的天真的方法可能会在 4 之前减少 5，但顺序只影响效率，而不影响正确性。 然而，不正确更新邻居或无法重新评估新创建的峰值的粗心实现可能会在优先级结构中留下陈旧的值，从而产生不正确的最终高度，例如留下一个比两个邻居都高的段，即使它应该在以后减少。 

当存在长的平坦高原时，会出现另一种边缘情况。 例如，`[3, 3, 10, 3, 3]`中心反复塌陷，一旦塌陷，高原结构就会发生变化。 如果更新未正确合并，重复处理同一平台会导致冗余工作，并可能破坏性能假设。 

## 方法

 暴力解释很简单：重复扫描所有段以找到最高的有效段，然后应用局部归约规则并更新数组。 每个操作都需要 O(n) 来找到最大值，并且在最坏的情况下可能存在 O(n^2) 级联减少，特别是当每次减少在以不同形式再次合格之前仅稍微减少一个峰值时。 当 n 很大时，这立即变得太慢。 

关键的结构观察是，该过程始终作用于当前全局最大分段，并且每个分段仅通过由其邻居定义的一系列有效“支撑”高度向下过渡。 一旦我们接受唯一有意义的事件是“一个段改变高度并可能与相同高度的邻居合并”，问题就变成了段上的事件模拟，而不是单独的更新。 

我们没有将数组视为单独的点，而是将其压缩为相同高度的最大连续段。 每个操作都可能拆分或合并这些段，但每次合并都会严格减少段的数量。 如果我们总是处理可用的最高段，我们可以将所有段维护在以高度为键的最大优先级队列中。 当处理一个段时，它会被一个新段替换，该新段的高度将成为其邻居的最大值，并且相邻的等高段将被合并。 由于每次合并都会减少段总数，并且每个段都会被插入或删除对数次，因此整体复杂度变得拟线性。

 ## 算法演练

 我们首先将初始数组压缩为连续相等值的段。 这种压缩是必不可少的，因为只有段边界可以改变； 平坦区域的内部点的行为相同。 

然后，我们维护按高度排序的最大段堆。 每个堆条目代表一个可能减少的候选段。 除此之外，我们还维护段之间的邻接指针，以便我们可以有效地查询左右邻居。 

我们还为每个段维护一个有效性标记，因为旧的堆条目在合并后可能会变得过时。 

流程如下。 

1. 通过扫描一次数组并对连续的相等值进行分组来构建初始段。 每个段都以双向链接结构存储其高度及其左右邻居。 
2. 将所有段插入按高度键的最大堆中。 每个堆条目还带有一个版本标识符，因此我们可以在合并后检测陈旧的条目。 
3. 当堆不为空时，提取高度最大的段。 如果它已被先前的合并失效，则跳过它。 
4. 对于提取的段，确定其当前的邻居。 如果两个邻居都存在并且与当前线段高度相等，则该线段无需任何操作，可以忽略。 这反映出它已经局部稳定。 
5. 否则，将新高度计算为存在的两个邻居的最大值。 这是该过程的强制规则：该段塌陷到最强的相邻支撑。 
6. 用高度减小的新段替换该段。 如果它们现在共享相同的高度，这可能需要与左或右邻居合并。 
7. 任何合并后，更新邻接指针并使旧的堆条目无效。 将新合并的段插入回堆中。 

当堆无法再产生可减少的段时，算法终止，这意味着每个段与其邻居局部一致，并且没有更高的峰值保持可移动。

关键的不变量是堆中的每个段代表演化数组中当前连续的相同高度的块。 每个操作都通过确保任何高度减小严格遵守局部邻居约束来保持正确性。 由于每次缩减要么合并段，要么严格减小最大高度，因此该过程无法循环并且必须终止。 堆始终公开全局最高的剩余段，因此不会错过任何有效的减少，并且本地更新保证未来的状态与早期的合并保持一致。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("h", "l", "r", "alive", "id")
    def __init__(self, h, i):
        self.h = h
        self.l = None
        self.r = None
        self.alive = True
        self.id = i

import heapq

def solve():
    a = list(map(int, input().split()))
    if not a:
        return

    # build segments
    nodes = []
    i = 0
    seg_id = 0

    while i < len(a):
        j = i
        while j < len(a) and a[j] == a[i]:
            j += 1
        node = Node(a[i], seg_id)
        seg_id += 1
        nodes.append(node)
        i = j

    # link
    for i in range(len(nodes) - 1):
        nodes[i].r = nodes[i + 1]
        nodes[i + 1].l = nodes[i]

    # heap (max via negative)
    pq = []
    for node in nodes:
        heapq.heappush(pq, (-node.h, node.id, node))

    def valid(node):
        return node is not None and node.alive

    while pq:
        neg_h, _, node = heapq.heappop(pq)
        if not node.alive:
            continue

        l = node.l
        r = node.r

        # already stable if both neighbors exist and are not higher influence
        if l and r and node.h <= max(l.h, r.h):
            continue

        new_h = 0
        if l:
            new_h = max(new_h, l.h)
        if r:
            new_h = max(new_h, r.h)

        node.h = new_h

        # merge left
        if l and l.h == node.h and l.alive:
            l.alive = False
            node.l = l.l
            if node.l:
                node.l.r = node
            l = node

        # merge right
        r = node.r
        if r and r.h == node.h and r.alive:
            r.alive = False
            node.r = r.r
            if node.r:
                node.r.l = node

        heapq.heappush(pq, (-node.h, node.id, node))

    # reconstruct (if needed)
    res = []
    cur = nodes[0]
    while cur.l:
        cur = cur.l
    while cur:
        res.extend([cur.h])
        cur = cur.r

    print(*res)

if __name__ == "__main__":
    solve()
```该代码首先将数组压缩为最大段，以便更新不会重复触及内部点。 每个段都作为具有左指针和右指针的节点进行跟踪，这允许恒定时间邻域查询。 

优先级队列确保最高的段始终首先被处理，符合贪婪规则。 这`alive`标志可防止合并后重复使用过时的段。 

当处理一个段时，它的高度会根据邻居重新计算，并且立即合并可确保表示保持最小。 重建步骤从最左边的段开始，并将最终的压缩表示扩展回输出形式。 

必须小心处理过时的堆条目，因为同一段可能存在多个版本。 跳过无效节点对于正确性至关重要。 

## 工作示例

 考虑数组`[1, 5, 2, 4, 1]`。 

我们从细分开始`[1] [5] [2] [4] [1]`。 堆总是首先选择高度为 5 的段。 它减少到`max(1,2) = 2`，生产`[1] [2] [2] [4] [1]`。 合并后我们得到`[1] [2] [4] [1]`。 接下来，段 4 被处理并变为`max(2,1) = 2`，生产`[1] [2] [2] [1]`，然后合并产量`[1] [2] [1]`。 该过程持续直至稳定。 

| 步骤| 选定的部分| 邻居最大| 数组状态 |
 | --- | --- | --- | --- |
 | 1 | 5 | 2 | [1, 2, 2, 4, 1] |
 | 2 | 4 | 2 | [1,2,2,1]|
 | 3 | 2 | 1 | [1, 1, 1] |

 该迹线显示了峰如何向其局部支撑塌陷以及重复合并如何减少结构直至达到均匀性。 

现在考虑`[3, 3, 10, 3, 3]`。 

| 步骤| 选定的部分| 邻居最大| 数组状态 |
 | --- | --- | --- | --- |
 | 1 | 10 | 10 3 | [3, 3, 3, 3, 3] |

 这表明单个主峰在一次操作中塌陷为平坦的平台，之后不再发生进一步的变化。

 ## 边缘情况

 一个重要的边缘情况是单元素输入，例如`[7]`。 没有邻居，因此不可能减少。 该算法立即将该段识别为隔离段并以相同的值终止，因为没有堆操作可以产生有效的归约。 

另一个边缘情况是完全均匀的数组，例如`[4, 4, 4, 4]`。 压缩产生单个段，并且堆永远不会触发任何减少，因为没有更高或更低的邻居来引发变化。 输出保持不变。 

第三种边缘情况涉及对称峰值，例如`[1, 5, 1]`。 中心峰减小为`1`，合并成一个平面段。 堆确保这种情况立即发生，并且不会持续存在中间不一致状态，因为过时的条目在处理之前已被过滤掉。
