 ## 解决方案
 ## 问题理解

 我们得到了一系列非负整数，表示沿线可用的雪量。 任务是选择该序列的三个连续或不重叠的部分，并将它们分配给三个雪球，排序后雪球的大小分别表示为 s1、s2 和 s3，使得 s1 ≤ s2 ≤ s3。 该约束不是任意的：构造必须满足生长条件，其中中间的雪球至少是最小的雪球的两倍，并且最大的雪球至少是中间的雪球的两倍。 

根本问题不是简单地选择任何三个部分，而是以尊重这些乘法约束的方式将可用雪划分为三个部分，同时仍然使用数组的不相交范围。 输出是在这些规则下可实现的最佳配置，通常根据问题陈述中编码的隐式目标进行优化，这减少了寻找在加倍约束下最大化可行性的有效分割。 

输入大小意味着数组最多包含 100,000 个元素。 任何直接尝试所有三元组切割位置的方法都会涉及分割点上的三次或二次行为，并且速度很快。 如果每次检查都是线性的或涉及重新计算，即使是对两个剪切位置的 O(n^2) 扫描也将成为边界。 

关键的结构边缘情况是，当雪分布不均匀时，贪婪或局部分裂会失败。 例如，如果大多数雪较早集中，则天真的尝试可能会形成有效的小 s1 和 s2，但留下的剩余质量不足，导致 s3 ≥ 2s2，即使稍微移动的分区会成功。 相反，将 s1 推得太大可能会导致无法满足 s2 ≥ 2s1，即使稍后存在有效配置。 

最小的说明性失败是像 [1, 1, 100, 100, 100] 这样的数组。 天真的贪婪分割可能会选择 s1 = 1，s2 = 1，留下 s3 = 300，这违反了 s2 ≥ 2s1，因为 1 ≥ 2 是假的，即使通过不同分组存在有效的排列。 

## 方法

 暴力方法固定两个分割点 i 和 j，并将段 [1..i]、[i+1..j]、[j+1..n] 分配给所有可能排列中的 s1、s2、s3。 对于每个分区，我们计算段总和，并在对它们进行排序后检查加倍约束是否成立。 这需要 O(n^2) 个 (i, j) 选择，并且可以使用前缀和在 O(1) 内完成计算段和，从而给出 O(n^2) 总时间。 然而，问题结构比任意分区更具限制性，因为约束强制段大小之间的单调关系。 

关键的观察是，一旦我们确定了一个雪球的候选边界，假设我们决定 s1 在哪里结束或 s3 在哪里开始，剩下的可行性检查就会变得单调。 如果我们增加一个片段的大小，下一个片段所需的阈值就会朝着可预测的方向移动。 这种单调性允许对段端点进行二分搜索，而不是线性扫描。 

我们利用前缀和，以便可以在 O(1) 中计算任何段和，然后对于固定分割点 l，我们可以二分搜索下一个边界 r，使得中间段满足加倍约束。 对称参数适用于第三段。 由于数组中存在 s1、s2、s3 的多个有效顺序，因此我们通过反转数组并重新应用相同的逻辑来隐式考虑所有排列。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 太慢了|
 | 前缀+二分查找| O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

我们使用前缀和，以便可以在恒定时间内计算任何间隔的总和。 然后，我们迭代边界 l 的选择，该边界定义了第一个选定段的末尾。 这个 l 代表一个雪球结束、下一个雪球开始的候选位置。 

对于每个固定的 l，我们将前缀 [1..l] 视为潜在的雪球大小，然后在 [l+1..n] 中搜索有效的第二个边界 r。 第二个边界的目标是确保下一个段足够大以满足相对于第一个段的加倍约束。 由于段和随着 r 的增加而增加，因此可行性成为 r 上的单调谓词。 

我们对 r 使用二分搜索来查找满足约束的最小或最大位置，具体取决于我们当前正在建模的雪球排序。 一旦 r 被固定，剩下的后缀就决定了第三个雪球，我们检查它是否满足最终的约束。 

由于该问题需要考虑 s1、s2、s3 的所有排列，因此我们对所有逻辑角色分配重复相同的过程。 我们观察到，反转数组允许我们交换“基于前缀”和“基于后缀”的角色，而不是显式枚举六种排列，从而有效地覆盖对称情况。 

在扫描所有可能的 l 并对 r 应用二分搜索后，我们跟踪是否存在任何有效配置。 

### 为什么它有效

 正确性取决于前缀和的单调行为。 当我们扩展段边界时，段总和永远不会减少。 这确保像 s2 ≥ 2s1 或 s3 ≥ 2s2 这样的约束成为搜索空间上的单调谓词。 一旦配置在某个 r 处有效，所有进一步的扩展对于该特定的不等式方向仍然有效，这正是允许二分搜索隔离过渡点的原因。 因为所有角色都是通过 l 迭代和反转对称性覆盖的，所以不会遗漏任何有效分区。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    def get(l, r):
        return pref[r] - pref[l]

    def check(arr):
        n = len(arr)
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + arr[i]

        def seg(l, r):
            return pref[r] - pref[l]

        for l in range(1, n + 1):
            s1 = seg(0, l)
            
            lo, hi = l + 1, n - 1
            while lo <= hi:
                mid = (lo + hi) // 2
                s2 = seg(l, mid)
                s3 = seg(mid, n)

                if s2 >= 2 * s1:
                    hi = mid - 1
                else:
                    lo = mid + 1

            if lo < n:
                s2 = seg(l, lo)
                s3 = seg(lo, n)
                if s2 >= 2 * s1 and s3 >= 2 * s2:
                    return True

        return False

    if check(a) or check(a[::-1]):
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```该实现为 O(1) 范围查询构建前缀和。 这`check`函数测试数组的一个方向，而反向调用则涵盖对称排列。 

对于每个前缀端点 l，我们将 s1 计算为第一个段的总和。 然后我们对第二个切点进行二分搜索。 二分查找中使用的谓词强制执行第一个不等式，确保 s2 相对于 s1 足够大。 找到候选分割后，我们显式验证两个约束，包括涉及 s3 的第二个不等式，因为该不等式取决于确切的分割。 

反转步骤至关重要，因为约束的结构是有方向的。 如果没有它，则只能达到一半的有效配置。 

## 工作示例

 考虑一个输入数组 [1, 2, 8, 16, 40]。 

我们首先计算前缀和：[1,3,11,27,67]。 

对于 l = 1，s1 = 1。我们对 r 进行二分搜索。 假设 r = 2 给出 s2 = 2，但 2 ≥ 2 失败，因此我们展开。 当 r = 3、s2 = 10 时，现在有效。 那么 s3 = 56，满足 56 ≥ 20，所以这个配置是有效的。 

| 我| r（发现）| s1 | s2 | s3 | s2 ≥ 2s1 | s3 ≥ 2s2 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 3 | 1 | 10 | 10 56 | 56 是的 | 是的 |

 这显示了早期分裂失败但稍大的中间段恢复了可行性的情况。 

现在考虑[5,5,5,5]。 

对于任何 l，s1 相对于可能的 s2 和 s3 增长得太快。 即使我们选择平衡分割，加倍约束也会立即失败。 

| 我| r | s1 | s2 | s3 | 有效 |
 | --- | --- | --- | --- | --- | --- |
 | 2 | 3 | 10 | 10 5 | 5 | 没有|

 这表明单调搜索正确地穷尽了所有可能性，而不会错误地接受无效分区。

 ## 边缘情况

 一个边缘情况是当第一个段与其余段相比非常小时，这可以创建多个有效的 r 值。 二分搜索正确地处理了这个问题，因为谓词保持单调：一旦 s2 跨过阈值，它对于较大的 r 保持有效，因此我们永远不会错过最小可行边界。 

另一个边缘情况是当最佳分割大量使用后缀时，这就是需要反转数组的原因。 对于输入 [100, 1, 1, 1, 1]，正确的配置将较大的值放在末尾作为 s3。 在反向数组上运行该算法会公开等效的基于前缀的结构，并且相同的二分搜索逻辑可识别可行性。 

当边界位于极端位置（例如 l = n - 2）时，会出现最终的边缘情况。在这种情况下，二分搜索空间很小，但算法仍然可以正确检查最后两个段是否满足约束，而不需要特殊的大小写。
