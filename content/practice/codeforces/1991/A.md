 ## 解决方案
 ## 问题理解

 给定一个奇数长度的数组，我们通过一次删除两个相邻元素来重复压缩它，直到只剩下一个值。 每次删除都会删除一个连续的对，其他所有内容都会一起移动。 目标是选择删除的顺序，使得最终的剩余值尽可能大。 

查看该过程的另一种方式是，我们将数组的元素配对，其中每个操作都会删除一个相邻的对，最终恰好有一个元素未配对。 关键的限制是配对在被删除时必须是相邻的，但由于数组缩小，有效的配对结构是灵活的。 

每个测试的约束很小，n 最多为 99，但测试用例最多为 1000 个。 这立即表明任何高达 O(n^2) 甚至 O(n^3) 的解决方案都是可以接受的，而对所有删除序列的指数探索是不必要的，并且在最坏的情况下会太慢，因为重复删除相邻对的方法数量随 n 组合增长。 

一个微妙的点是，最后剩余的元素不一定必须位于数组的中心。 早期删除可以改变元素，这意味着最终的幸存者可能来自不同的结构位置，具体取决于删除的安排方式。 总是删除局部最小或最大相邻对的天真的贪婪方法会失败，因为局部选择会影响哪些元素仍可用于最后一步。 例如，在`[1, 3, 2]`，去除`1 3`导致`2`，同时去除`3 2`导致`1`，所以最终的答案取决于全局选择，而不是局部排序。 

另一个微妙的边缘情况是最大元素因需要特定奇偶校验才能到达而被“阻塞”。 然而，因为 n 是奇数，所以只有一个位置会保留下来，并且操作的结构确保我们始终可以路由删除，以便如果我们正确管理配对，则可以保留任何选定的位置。 

## 方法

 暴力方法将模拟所有可能的相邻删除序列。 在每一步中，我们选择要删除的任何相邻对，对结果数组进行递归，并跟踪最佳的最终值。 这是正确的，因为它探索了每个有效的操作序列。 然而，分支因子一开始是 O(n)，然后是 O(n−2)，依此类推，从而导致阶乘增长。 即使 n = 25 这也是不可行的，而这里 n 可以是 99，这使得它完全不可能。 

关键的观察是，我们并不真正对中间数组感兴趣，只对哪个元素能够在所有对删除中幸存下来感兴趣。 每个操作恰好删除两个元素，因此该过程总共删除 n−1 个元素，留下一个幸存者。 这意味着每个有效过程相当于选择 n−1 个元素进行删除，这样随着时间的推移，删除的元素可以排列成相邻对。 

关键的结构见解是，如果我们确保除它之外的所有元素都可以以符合邻接约束的方式配对，则始终可以从任何位置选择幸存者。 因为我们可以重复删除相邻对，所以只要不违反奇偶校验约束，我们总是可以从两侧“切掉”元素，直到只剩下所选元素。 

由于仅保留一个元素，并且我们始终可以安排删除，以便任何选定的元素都可以生存，因此答案简化为选择数组中的最大元素。 

这令人惊讶，只是因为该操作看起来具有限制性，但实际上它的功能强大到足以消除除任意选择的位置之外的所有内容。

 ## 算法演练

 1. 对于每个测试用例，扫描数组的所有元素。 目标是确定哪个元素可以成为最佳删除后的最终幸存者。 
2. 迭代数组时跟踪迄今为止看到的最大值。 每个元素都是候选幸存者，因为存在一系列相邻的删除来保留它。 
3. 扫描全数组后，输出最大值。 

唯一重要的推理步骤是为什么跟踪最大值就足够了：每个元素作为最终幸存者都可以独立实现，因此可实现的最佳结果就是最大的可用值。 

### 为什么它有效

 每个操作恰好删除两个相邻元素，因此该过程将数组大小一次减少两个，直到剩下一个。 任何选定的元素都可以通过始终删除外部区域上的相邻对来保护，并逐渐向其缩小数组。 由于除非配对，否则没有任何操作会强制删除特定元素，因此我们始终可以通过在其周围构建删除来避免对所选最大元素进行配对。 这使得每个位置都可以作为幸存者，因此最佳策略是保留最大值。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(max(a))
```该代码独立读取每个测试用例并计算数组的最大值。 核心思想是不需要模拟，因为答案仅取决于可实现的最佳幸存者值，而不是删除顺序。 

唯一重要的实现细节是使用快速输入，因为最多可以有 1000 个测试用例。 这`max`函数的运行时间复杂度为 O(n)，给定约束就足够了。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        out.append(str(max(a)))
    return "\n".join(out)

 ## 边缘情况

 对于单元素数组，不可能进行任何操作，并且该元素已经是答案。 该算法直接返回它，因为`max([x])`等于`x`。 

对于最大值位于端点的数组，例如`[9, 1, 2, 3, 4]`，算法仍然返回 9。从概念上讲，我们可以从右侧开始重复删除对，始终保留第一个元素，因此 9 可以保留到最后。 

对于像这样的图案`[1, 100, 1, 100, 1]`，即使最大值被较小的值分隔，该过程也允许我们消除选定的 100 个周围的所有未选择的元素。由于我们只需要一个幸存者，因此我们可以保留 100 个中的一个，并且算法正确地输出 100。
