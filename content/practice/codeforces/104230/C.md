 ## 解决方案
 ## 问题理解

 我们得到一个隐藏的无向图$n$标记的节点。 该图的结构称为设计 0，但我们从未直接显示其边缘。 相反，我们可以查询两个节点是否通过某种路径连接，这意味着我们只获得连接信息，而不是边缘信息。 

关键的问题是，每次我们查询当前版本的图中未连接的两个节点时，系统都会通过在这两个节点之间添加直接边来永久修改该版本，并为此修改后的图返回一个新的设计索引。 如果节点已经连接，系统只会应答，不会修改任何内容。 

因此，每个查询同时提供信息，并可能更改该设计版本的未来查询。 我们可以查询任何以前创建的设计版本，包括原始设计 0，但较新设计的结构取决于早期不成功的连接查询。 

目标不是重建精确的原始边缘集。 相反，我们必须输出每对节点之间的连接关系与设计 0 匹配的任何图。换句话说，我们只需要重现隐藏图的连接组件，而不是其内部布线。 

限制条件$n \le 200$根据子任务的不同，最多大约 2000 到 20000 个查询表明$O(n^2)$策略可能是有意的，因为我们可以负担得起$10^4$总共查询。 这也表明我们应该避免在许多不断发展的设计中重复探索同一对节点的任何策略，因为如果不加以控制，每个失败的查询都会改变结构并使推理不稳定。 

一个微妙的陷阱是假设查询是静态的。 他们不是。 如果我们在之前强制使用额外边缘的设计中测试连接性，我们可能会意外地折叠组件并破坏未来答案的含义。 例如，如果我们首先发现 1 和 2 在设计 0 中断开，但在它们连接的地方创建了一个新的设计 1，那么稍后查询设计 1 将错误地将它们报告为连接，即使它们在设计 0 中断开。这意味着所有有意义的推理必须仅锚定在设计 0 上，并且我们必须避免使用变异设计进行结构发现。 

## 方法

 一个蛮力的想法是检查每一对$(i, j)$在设计0中并直接决定是否在输出图中包含它们之间的边。 然而，我们实际上无法访问直接边缘查询。 我们只有一个连接预言机，当它遇到断开连接的对时，它可能会改变状态。 如果不仔细控制，任何简单的成对探测都会变得不可靠。 

如果我们暂时忽略变异并假设查询是纯粹的连接性检查，我们可以选择一个根节点并通过 BFS 式探索计算所有连接的组件：对于每个新节点，测试它是否连接到组件的已知代表。 那需要$O(n^2)$查询就足够了。 

真正的困难在于，对设计 0 的查询是安全的，但对任何创建的设计的查询可能会永久改变该设计。 因此，关键的观察结果是，我们永远不应该查询除设计 0 之外的任何内容。如果我们将所有连接检查限制为设计 0，那么系统永远不会创建新的边，并且交互将成为标准的连接预言。 

一旦我们在设计 0 中拥有稳定的连接，任务就减少到识别每个连接组件的生成林。 我们不需要所有的边，只需要足够的边来保持每个组件内部的连接性。 最简单的方法是在每个组件上构建 BFS 或 DFS 树。 每次我们发现一个连接到当前组件但尚未访问的新节点时，我们都会通过输出图中的发现边连接它。 然而，我们没有给出邻接表，因此我们通过测试对来模拟可达性。 

因此，我们可以将节点 1 视为起点，然后迭代所有节点，并使用设计 0 的连接性检查将它们分组为组件。对于每个未访问的节点，我们将其附加到已知组件的代表（如果已连接）； 否则它会启动一个新组件。 识别组件后，我们通过将组件中的每个节点连接到该组件中的第一个节点来输出每个组件内的生成树。 这是有效的，因为在设计 0 中同一组件中的所有节点都是相互可达的，因此添加星形结构可以保持连接等效性。 

这避免了对隐藏图边缘的任何依赖，并且仅使用设计 0 上的连接谓词，该设计永远不会变异。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 使用易于突变的查询进行强力对探测 | O(n^2) 但不稳定 | O(n^2) | O(n^2) | 由于状态突变而错误 |
 | 组件检测+跨星构建| O(n^2) | O(n^2) | O(n) | 已接受 |

 ## 算法演练

 1. 将节点 1 固定为参考并假设它属于第一个组件。 维护一个组件代表列表和一个标记每个节点是否已分配给组件的数组。 这为我们提供了连接分组的稳定锚点。 
2.对于每个节点$i$从 2 到$n$,查询节点1与节点的连通性$i$使用设计0。如果结果是连接的，则分配$i$到与节点 1 相同的组件。否则，启动一个新组件$i$作为其代表。 这样做的原因是连接性是一种等价关系，因此同一连接组件中的成员资格完全由单个代表的可达性决定。 
3. 通过维护代表列表将这一想法扩展到所有组件。 对于每个新节点$i$，将其与每个现有代表进行比较，直到找到匹配项或不存在匹配项。 这保证了每个节点都准确无误地放置在一个组件中。 
4. 识别出所有组件后，通过在每个组件内形成一个星形来构建输出图。 对于每个组件，选择其代表节点$r$，并连接所有其他节点$v$在该组件中$r$。 这会产生$|C| - 1$每个组件的边，这足以用于连接。 
5. 输出所有收集到的边`DescribeDesign`。 

关键的设计选择是我们从不查询除设计 0 之外的任何内容。这可以防止交互系统进入突变状态，确保所有答案都对应于原始隐藏图。 

### 为什么它有效

 无向图中的连通性将节点划分为不相交的等价类。 一旦我们正确识别这些类，每个类中的任何生成树都会保留完全相同的可达性关系：当且仅当它们位于同一原始组件中时，每对节点都保持连接。 由于该构造显式地为每个组件构建一个连接树并且不连接不同的组件，因此它再现了设计 0 的精确连接结构。

import sys
input = sys.stdin.readline

# Here we assume they exist.

def ToyDesign(n, max_ops):
    comp = [-1] * (n + 1)
    reps = []
    comps = []
    
    def get_comp(i):
        return Connected(0, 1, i)  # placeholder usage in explanation; real solution assumes design 0 queries only
    
    # We will actually assume pairwise check with design 0 only
    # Component detection
    for i in range(1, n + 1):
        assigned = False
        for idx, r in enumerate(reps):
            if Connected(0, r, i) == 0:
                comp[i] = idx
                comps[idx].append(i)
                assigned = True
                break
        if not assigned:
            comp[i] = len(reps)
            reps.append(i)
            comps.append([i])
    
    # Build spanning forest
    edges = []
    for group in comps:
        root = group[0]
        for v in group[1:]:
            edges.append((root, v))
    
    DescribeDesign(edges)

if __name__ == "__main__":
    n, max_ops = map(int, input().split())
    ToyDesign(n, max_ops)

一个微妙的实现限制是查询的数量。 在最坏的情况下，我们的表现约为$n^2$检查，这在最弱的子任务约束下是可以接受的。 

## 工作示例

 考虑一个简单的情况，其中节点$\{1,2,3\}$都已连接，并且节点$4$是孤立的。 

我们从空组件开始并按顺序处理节点。 

| 节点| 代表支票| 结果 | 组件分配|
 | ---| ---| ---| ---|

接下来考虑一个包含两个组件的图：{1,2} 和 {3,4,5}。 假设 3 是第一个发现的第二个分量的代表。 

| 节点| 检查与代表| 结果|
 | ---| ---| ---|
 | 1 | 新 | C0 = {1} |
 | 2 | 连接(1,2)=1 | C0 = {1,2} |
 | 3 | 连接(1,3)=0 | 新C1 |

 ## 边缘情况

 一种边缘情况是每个节点都被隔离。 在这种情况下，不同节点之间的每个连接查询都会返回断开连接，因此每个节点都成为自己的代表。 然后，该算法不输出任何边，这与正确的等价匹配，因为没有对连接。 

另一个边缘情况是全连接图。 每个节点都与第一个代表匹配，因此仅形成一个组件，并且输出成为星形。 即使原始图可能有许多边，星形仍保留完全的连通性等价性。 

最后一个微妙的情况是，组件是通过辅助代表较晚发现的。 即使节点未连接到第一个代表，它最终也会匹配到同一组件内的另一个代表，因为连接是可传递的。 即使没有邻接知识，这也保证了正确的分组。
