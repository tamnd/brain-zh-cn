 ## 解决方案
 ## 问题理解

 我们得到一个整数网格。 游戏中的移动会反复修改网格，直到不再可能移动为止。 关键的结构属性是，虽然值可能会在游戏中发生变化，但单元格之间的相对顺序永远不会改变。 如果一个细胞一开始就比另一个细胞小，那么它在整个过程中都会保持较小的状态。 

游戏总是朝着无法进一步移动的终端配置发展。 在此最终配置中，每个像元都有一个相邻像元，其值恰好小一（局部最小值除外）。 这迫使结构非常严格：每个单元格的值完全取决于它通过递减步长距局部最小值的距离。 

我们的目标不是模拟游戏，而是在假设双方都发挥最佳水平的情况下确定获胜者，其中获胜者取决于到达这个独特的终端网格所需的总移动次数是奇数还是偶数。 

网格尺寸符合建议的典型约束$N \times M$可以足够大，以至于不可能进行任何移动模拟。 任何尝试重复应用本地更新的方法都存在每次移动最多执行一次操作的风险，并且由于移动次数可以随所有值的总和缩放，因此网格大小很快就会变成二次或更糟。 

当所有值在其邻域中都已经最小时，就会出现微妙的边缘情况。 在这种情况下，从一开始就不可能采取任何行动，答案完全取决于奇偶校验零，这意味着第二个玩家立即获胜。 任何假设至少存在一步棋的解决方案都会错误地翻转获胜者。 

另一种边缘情况出现在各处值相等的网格中。 例如，填充有 5 的 2 x 2 网格没有严格递减结构来传播，因此它已经是终端。 尝试基于比较应用转换的简单模拟可能会错误地尝试更新并更改网格结构，从而产生错误的非零移动计数。 

## 方法

 游戏的暴力解释很简单：重复扫描网格，应用所有有效的移动，然后继续，直到无法移动为止。 每次移动都会使网格总和恰好减少 1，因此很容易证明正确性。 然而，此类移动的次数可以与网格上的总累积高度差一样大。 在最坏的情况下，网格的大小$N \times M$值高达$V$可以要求$O(NMV)$单个操作，并且每个操作都需要扫描或更新邻居，导致总体成本对于大量输入来说变得不可行。 

关键的观察是最终配置是唯一确定的，无需模拟任何动作。 排序约束意味着只有相对结构很重要，并且最终状态对应于为每个单元分配一个值，该值等于当移动穿过邻居时以该单元结束的最长严格递减路径的长度。 

这将问题转化为网格的图形解释，其中边缘隐式地从较高值变为较低值。 一旦我们意识到每个单元的最终值仅取决于其原始值较小的邻居，我们就可以按初始值的升序计算结果。 每个单元格变成其已计算的较小邻居的最大值加上一，或者如果不存在则为零。 

重建最终网格后，移动总数就是初始总和与最终总和之间的差。 由于每次移动都会将总和减少一，因此这种差异是精确的，仅奇偶性就决定了获胜者。

 ## 算法演练

 我们通过按原始值的升序处理单元来直接计算最终的稳定网格。 

1. 将所有网格单元及其坐标平铺到一个列表中，并按值对它们进行排序。 这确保了每当我们处理一个单元时，所有严格较小的邻居都已经被分配了它们的最终值。 
2.初始化一个新的网格`dp`大小相同，所有值均设置为零。 
3. 迭代排序的单元格。 对于每个单元格，检查其四个邻居。 在那些原始值严格较小的邻居中，取最大值`dp`价值。 
4. 指定当前单元格的`dp`值为 1 加该最大值。 如果没有邻居具有更小的原始值，则分配零。 
5.处理完所有单元格后，计算原始网格的总和与`dp`网格。 
6. 移动次数是这两个总和之间的差。 
7. 根据差值是奇数还是偶数来确定获胜者。 

排序背后的关键思想是，它强制执行与原始值结构一致的依赖顺序，防止任何单元依赖于尚未计算的状态。 

### 为什么它有效

 排序约束保证任何有效的转换都遵循值的初始严格排序。 因此，单元格最终值的每个有效依赖项都必须来自严格较小的原始值。 按排序顺序处理可确保在需要时已解决这些依赖关系。 

每个单元格的最终值代表以该单元格结束的严格递减邻接步骤的最长链。 这是独一无二的，因为任何偏差都会违反排序约束，或者无法满足每个非最小单元必须有一个邻居恰好少一个的最终条件。 

由于每次移动都会使总和恰好减少 1，并且该过程始终以这个唯一定义的配置结束，因此初始总和与最终总和之间的差异在所有有效序列中都是不变的。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [list(map(int, input().split())) for _ in range(n)]

    cells = []
    for i in range(n):
        for j in range(m):
            cells.append((g[i][j], i, j))

    cells.sort()

    dp = [[0] * m for _ in range(n)]

    for val, i, j in cells:
        best = 0
        for di, dj in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            ni, nj = i + di, j + dj
            if 0 <= ni < n and 0 <= nj < m:
                if g[ni][nj] < val:
                    if dp[ni][nj] > best:
                        best = dp[ni][nj]
        dp[i][j] = best + 1 if best > 0 or any(
            0 <= i + di < n and 0 <= j + dj < m and g[i + di][j + dj] < val
            for di, dj in ((1, 0), (-1, 0), (0, 1), (0, -1))
        ) else 0

    initial_sum = 0
    final_sum = 0

    for i in range(n):
        for j in range(m):
            initial_sum += g[i][j]
            final_sum += dp[i][j]

    diff = initial_sum - final_sum
    print("Busy Beaver" if diff % 2 == 1 else "Calico Bear")

if __name__ == "__main__":
    solve()
```该解决方案首先构建所有网格单元的排序顺序，以便依赖性解析始终有效。 这`dp`网格存储每个单元计算的最终稳定值。 对于每个单元格，我们只考虑具有严格较小原始值的邻居，因为只有那些单元格才能反向形成有效的递增链。 

一个微妙的细节是，我们必须区分“没有有效的较小邻居”和“具有零 dp 值的有效邻居”。 这就是为什么我们在分配非零值之前明确检查任何邻居是否合格。 

最后，我们计算初始总和与最终总和之间的差。 由于每次移动都会将总和减少一，因此这种差异给出了准确的移动次数，而奇偶性决定了获胜者。

 | 时间 |$O(NM \log (NM))$| 对所有细胞进行排序占主导地位，DP 传递是线性的 |

        n, m = map(int, input().split())
        g = [list(map(int, input().split())) for _ in range(n)]

                    best = max(best, dp[ni][nj])

    return solve()

 ## 边缘情况

 单个单元网格展示了最简单的可能配置。 由于没有邻居，该小区已经处于终端状态。 该算法为其分配 dp 值为零，因为不存在更小的邻居，并且初始和最终总和之间的差值为零，从而产生第二个玩家获胜。 

统一网格（例如所有值都相等）会暴露算法是否错误地尝试通过等值邻居传播链。 因为构造明确要求严格较小的邻居，所以不会发生任何转换，所有 dp 值保持为零，并且结果仅取决于零移动的初始奇偶性，再次产生第二个玩家获胜。 

从左上角到右下角严格增加的网格显示最大传播。 每个单元通过较小的邻居累积最长的递减步长链，并且 dp 值形成距最小区域的梯度反映距离。 该算法仅通过排序处理来正确构建这些依赖关系，确保不会过早使用未初始化的状态。
