 ## 解决方案
 ## 问题理解

 我们得到了一组容器，每个容器最初都装有一个由目标容器索引标记的弹珠。 每个容器一开始就只有一个弹珠，但弹珠不一定位于正确的位置。 目标是改造系统，使每个容器最终都持有属于它的弹珠，这意味着容器 i 最终必须仅与弹珠 i 相关联。 

可以进行两种操作。 一项操作交换两个容器的内容。 第二个操作将弹珠从一个容器合并到另一个容器中，有效地移动弹珠并可能清空容器。 任务是使用最少的操作次数达到正确的最终配置。 

关键的困难在于合并操作改变了系统中“存在”的结构，而交换操作仅重新排列目的地。 这意味着解决方案不仅仅是排序，而是控制相同结构的组件如何相互作用。 

输入大小足够大，以至于对容器或配置的任何二次或状态模拟方法都是不可行的。 任何重复模拟交换或重新计算不断发展的结构的可达性的解决方案都将超出时间限制。 该结构必须被压缩成诸如图形组件、循环或函数映射之类的东西，这些东西可以在接近线性或对数的时间内更新。 

一些边缘情况值得尽早隔离。 

如果所有目标值都不同，则根本不存在合并，并且问题会简化为使用交换对排列进行排序。 例如，如果 c = [2, 3, 1]，则配置是长度为 3 的单个循环，唯一有意义的操作是交换以中断循环，直到所有内容都变为不动点。 

如果许多值相同，合并就会变得强大。 例如，c = [1, 1, 1, 1] 允许积极地合并所有弹珠，并且交换结构变得微不足道，因为所有内容都可以通过合并代表进行重定向。 

当交换后“较晚”应用合并时，会出现微妙的失败情况，这可能会产生冗余操作。 另一个是，当合并到相同值的不同代表时，会改变导出图的结构，如果处理不当，可能会默默地增加交换成本。 

## 方法

 如果我们忽略合并，这个问题就变成了一个经典的排列修复任务。 每个容器都指向一个目标，形成一个函数图，其中每个节点的出度均为 1。 这分解成不相交的循环。 两个元素之间的交换有效地交换其传出边缘，这可以分割循环或合并循环，具体取决于应用的位置。 

在纯排列设置中，目标是将每个循环分解为自循环。 如果一个循环的长度为 k，则需要仔细选择 k − 1 次交换才能完全解决它。 这给出了总成本 n 减去周期数。 

当存在重复的目标值时，困难就开始了。 现在，多个容器对应于同一目的地，并且合并允许我们选择这些重复项的锚定位置。 我们可以考虑共享相同值的索引组，而不是每个索引一个节点，并且我们可以决定每个组中的哪个代表成为该值的活动“锚”。 

一个蛮力的想法是尝试所有可能的合并目的地选择，然后通过重建诱导函数图和计数周期来计算最终的交换成本。 重复组的数量呈指数级增长，因为每个组都可能选择不同的锚容器。 即使对于中等的n，这也是不可能的。

关键的结构见解是合并可以在交换之前排序，并且一旦所有合并都得到修复，交换问题再次简化为函数图。 每个值组都成为单个顶点，并且边从一个组指向包含其目标的组。 唯一剩下的问题是这个导出图可以保留多少个周期。 

一旦完成压缩，交换成本仅取决于该组图中的组件数量。 与链相比，每个周期贡献一个单位的节省，最佳行为是通过选择一致地对齐传出边缘的合并代表来最大化周期保留。 

这导致了彻底的简化：答案由一个图确定，该图的顶点是值组，其边遵循组之间的目标映射。 然后，交换成本完全由该图的循环分解确定。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 暴力合并分配+重新计算| 指数| O(n) | 太慢了 |
 | 构建群图+循环分解 | O(n) | O(n) | 已接受 |

 ## 算法演练

 我们首先对具有相同目标值的指数进行分组。 每个这样的组代表其弹珠最终想要进入相同颜色类别的所有容器。 

然后我们在这些组上构建一个有向图。 对于每个索引 i，我们查看其目标值 c[i]，并将包含 i 的组中的有向边添加到代表 c[i] 的组中。 该图每个节点只有一个出边，因为每个组都有一个由目标值引起的唯一目标组。 

接下来我们分析一下这个群图可以包含多少个周期。 该图中的每个周期都对应于一种结构情况，其中组可以对齐，以便交换可以最佳地解决它们。 相比之下，链条以死胡同结束，不可能进一步形成循环。 

我们使用标准函数图遍历来计算该组图中的循环数。 沿着其输出边缘跟踪每个未访问的节点，直到到达已访问的节点或检测到循环。 我们对每个发现的周期精确计数一次。 

最后，答案计算为组顶点数减去组图中的循环数。 这反映了这样一个事实：与独立破坏所有内容相比，每个周期可以节省一次交换，而链则不能提供这样的节省。 

### 为什么它有效

 提交合并后，每个值组的行为就像具有固定传出依赖性的单个原子节点。 系统变成一个功能图，其中交换操作仅影响循环结构，而不影响可达性。 每次交换要么通过拆分来增加周期数，要么通过合并来减少周期数，并且通过最大化最终结构中存活的周期数来实现最优性。 由于合并排序可以在不失一般性的情况下标准化，因此所有最优解都对应于某个固定的组图，并且该图的循环计数完全决定了最小交换成本。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = list(map(int, input().split()))

    # compress values into groups
    groups = {}
    gid = 0
    g = [0] * n

    for i in range(n):
        v = c[i]
        if v not in groups:
            groups[v] = gid
            gid += 1
        g[i] = groups[v]

    m = gid

    # build functional graph on groups
    nxt = [-1] * m
    indeg = [0] * m

    for i in range(n):
        u = g[i]
        v = groups[c[i]]
        nxt[u] = v
        indeg[v] += 0  # structure is functional; indeg not required for answer

    visited = [0] * m
    in_stack = [0] * m
    cycles = 0

    def dfs(u):
        nonlocal cycles
        path = []
        while True:
            if visited[u]:
                return
            visited[u] = 1
            in_stack[u] = 1
            path.append(u)
            v = nxt[u]
            if in_stack[v]:
                cycles += 1
                break
            if visited[v]:
                break
            u = v
        for x in path:
            in_stack[x] = 0

    for i in range(m):
        if not visited[i]:
            dfs(i)

    print(m - cycles)

if __name__ == "__main__":
    solve()
```该解决方案首先将相同的值压缩为组标识符。 这是必要的，因为具有相同目标的所有弹珠在合并时都可以互换，因此单独区分它们只会增加状态大小，而不会改变结果。 

下一步将构建这些组的函数图。 每个组都有一个唯一的出边，该出边由任何代表性元素的目标值确定。 由于组中的所有元素共享相同的值，因此映射是一致的。 

循环计数是通过对功能图进行 DFS 式遍历来完成的。 每次我们遇到当前递归堆栈中已有的节点时，我们都会检测到一个循环。 循环次数是跨组件累积的。 

最终的表达式 m−cycles 对应于优化安排合并后所需的最小交换操作次数。 

## 工作示例

 ### 示例 1

 考虑 c = [2, 2, 3]。 

我们组成组：group(2) = A，group(3) = B。所以 m = 2。 

转换为 A → A（因为 2 映射到 2），以及 B → A（因为 3 映射到 2 组）。 

遍历过程为：

 | 步骤| 节点| 下一页 | 行动| 周期|
 | ---| ---| ---| ---| ---|
 | 1 | 一个 | 一个 | 检测到自环 | 1 |
 | 2 | 乙| 一个 | 导致进入访问周期| 1 |

 我们找到了一个循环，所以答案是 2 − 1 = 1。 

这说明，尽管B依赖于A，但只存在一个结构环，最优合并后只需要进行一次交换。 

### 示例 2

 考虑 c = [1, 2, 1, 2]。 

1 组为 A 组，2 组为 B 组，因此 m = 2。 

边是 A → A 和 B → B，产生两个自循环。 

| 步骤| 节点| 下一页 | 行动| 周期|
 | ---| ---| ---| ---| ---|
 | 1 | 一个 | 一个 | 循环| 1 |
 | 2 | 乙| 乙| 循环| 2 |

 答案是 2 − 2 = 0。 

这对应于已经稳定的结构，其中每个组形成一个固定点。

 ## 边缘情况

 最小单节点情况（例如 c = [1]）立即在群图中形成自循环，因此 m = 1 且周期 = 1，从而提供零次操作。 该算法正确地将其视为具有单个不动点的简并函数图。 

像 c = [x, x, x, x] 这样完全统一的情况会将所有节点折叠为一组。 该组映射到自身，恰好产生一个周期，因此交换成本为零，符合合并后所有内容都已对齐的事实。 

具有所有不同值的类似排列的情况会产生 m = n 组和标准循环分解。 每个周期都会减少一次交换，与函数图的经典结果相匹配。
