 ## 解决方案
 ## 问题理解

 我们得到一个由两种字符组成的字符串，其中一种充当结构标记，另一种则形成重复模式。 任务是决定字符串是否可以以非常严格的方式解释：每次遇到特殊字符`M`，从它到下一个的所有内容`M`必须由子字符串的一个或多个连续副本组成`IT`。 

所以字符串被有效地划分为`M`。 连续之间的每个段`M`字符，以及最后一个后面的后缀`M`，必须是模式的非空重复`IT`。 这些段之外的字符在这个问题中不存在，因此有效性完全取决于每个这样的段是否可以分解为`"IT"`重复一次或多次，没有剩余物。 

输入是单个字符串，输出是一个决策：整个字符串是否满足这个结构约束。 

此处未明确说明约束，但预期的解决方案描述假设对字符串进行线性处理。 这意味着 10^5 个字符左右的典型限制，这会立即排除任何二次方法，例如重复重新检查子字符串或尝试所有分段。 任何解决方案都必须扫描字符串恒定的次数。 

一个微妙的失败案例来自于忽视对齐。 例如，考虑`"MITITMII"`。 该段`"ITIT"`是有效的，但是`"II"`不是，即使这两个字母在其他地方成对出现。 一种简单的方法，仅检查计数或仅检查是否存在`I`和`T`会错误地接受无效段。 如果我们不强制重复是连续的，则会出现另一种失败情况：`"ITTI"`包含正确的多组字符，但不由以下组成`"IT"`块。 

## 方法

 暴力策略将对待每个`M`作为边界并通过尝试消费来验证下一个段`"IT"`贪婪地配对或通过重复重新计算子字符串匹配。 在最坏的情况下，如果字符串主要由`I`和`T`稀疏之间`M`s，我们可能会多次重复扫描相同的字符，从而导致二次行为。 

关键的观察是每个片段都是独立的，并且片段内的每个角色恰好参与一个潜在的`"IT"`一对。 这表明我们可以处理每个段一次并在一次传递中验证它，而不是重复检查子字符串。 一旦我们离开`M`，我们知道我们必须读取一系列`"ITITIT..."`直到下一个`M`或结束，所以我们简单地通过成对检查字符来贪婪地验证这个结构。 

这将问题简化为具有简单状态的线性扫描：我们期望`I`， 然后`T`，重复，任何偏差都会立即使字符串无效。

 ## 算法演练

 我们从左到右处理字符串，同时尊重由`M`。 

1. 从字符串的开头开始扫描。 我们对待每一个`M`作为启动新验证块的重置点。 这很重要，因为每个块必须独立地满足重复规则。 
2.当我们遇到一个`M`，我们移动到下一个字符并开始验证必须完全包含的段`"IT"`重复。 要求立即启动`M`确保我们不允许空前缀或格式错误的前缀。 
3. 在一个段内，我们成对地检查字符。 有效对的第一个字符必须是`I`。 如果不是，则该字符串立即无效，因为不允许重新排列。 
4. 阅读完后`I`，我们必须看到一个`T`紧随其后。 下一个字符是否缺失`T`，我们拒绝该字符串。 这强制执行了固定结构`"IT"`作为原子块。 
5.我们继续消费`"IT"`配对直到我们击中另一个`M`或到达字符串的末尾。 如果我们恰好停在边界处，则该段有效； 否则，段内的任何剩余字符都表示不完整的对，这是无效的。 
6. 对由 分隔的所有段重复此过程`M`。 如果所有段都通过验证，则该字符串有效。 

### 为什么它有效

 该算法保持不变，即每当我们在一个段内时，自上次以来消耗的字符数`M`始终是偶数并且已被验证为有效`"IT"`对。 每一步都会将此不变量扩展恰好两个字符。 因为每个字符只被消耗一次，并且段之间严格由`M`，不能存在跨段依赖性。 因此，任何违规都必须在本地表现为一对内的不匹配，算法会立即检测到。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

i = 0
while i < n:
    if s[i] == 'M':
        i += 1
        while i < n and s[i] != 'M':
            if i + 1 >= n:
                print("NO")
                sys.exit(0)
            if s[i] != 'I' or s[i + 1] != 'T':
                print("NO")
                sys.exit(0)
            i += 2
    else:
        print("NO")
        sys.exit(0)

print("YES")
```该代码直接反映了基于段的逻辑。 外循环在字符串中移动，每次看到`M`，它切换到段的验证模式。 在该段内，指针以两步前进，强制执行严格的`"IT"`配对。 边界检查确保我们不接受段末尾不完整的对。 

一个常见的实现陷阱是忘记强制段在之后立即开始`M`。 条件`else: print("NO")`保证有效段上下文之外的任何字符都会使字符串无效。 另一个微妙的问题是忘记检查`i + 1 >= n`，这可以防止在读取超出字符串范围的内容时`I`出现无匹配项`T`。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    backup = sys.stdout

 ## 边缘情况

 一种边缘情况是由单个组成的字符串`M`。 算法立即进入一个段并没有发现无效的`"IT"`对，因此它接受它为有效，因为没有违反重复规则。 

另一个边缘情况是输入开头`I`或者`T`在任何之前`M`。 例如`"ITM..."`或者`"TM..."`被立即拒绝，因为每个有效的结构必须仅在之后开始一个段`M`，并且没有独立的`"IT"`在该上下文之外是允许的。 

第三种边缘情况是以单个剩余字符结尾的段。 为了`"MITI"`，食用后`"IT"`，最后一个`I`没有伙伴`T`，边界检查发现了这一点，因为`i + 1`超过段限制，产生拒绝。
