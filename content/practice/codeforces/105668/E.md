 ## 解决方案
 ## 问题理解

 我们得到一个随着时间的推移而更新的数组，我们必须回答有关在涉及“缺失”数字的特定规则下可以安全地使用子数组中的哪些值的查询。 

交互的结构很简单：数组通过点更新而改变，每个查询要求我们输出一个保证满足相对于数组所选段的条件的数字。 关键的隐藏思想是，答案仅取决于当前数组是否包含固定范围内的所有值，如果不包含，则任何缺失值都将成为通用答案。 否则，当没有丢失任何内容时，我们必须确保选择查询区间之外的内容。 

约束足够大，以至于为每个查询重新计算频率或扫描范围会太慢。 任何通过迭代来检查间隔的解决方案在最坏的情况下都会降级为二次行为，当数组大小和操作数量都很大时，这是不可接受的。 这迫使我们维护可以在每次操作中以对数或恒定时间更新的全局信息。 

当数组恰好是从 1 到 N 的值的排列时，就会出现微妙的边缘情况。在这种情况下，不存在全局缺失值，因此始终返回“某些缺失数字”的幼稚策略会失败，因为不存在任何值。 如果我们总是选择查询范围之外的固定索引而不跟踪更新，则会出现另一种失败情况，因为无论该索引是否有效，更新都可能会发生变化。 

例如，如果数组变成像这样的排列`[1, 2, 3]`，没有缺失的数字。 如果一个简单的解决方案假设范围更大或没有仔细限制，它可能会错误地尝试输出“缺失”值，例如 4。 在这种情况下，正确的行为必须完全改变策略。 

## 方法

 蛮力的想法很简单。 对于每次更新，我们直接修改数组。 对于每个查询，我们扫描相关区间并计算出现的值，然后确定是否缺少从 1 到 N 的某个值，或者我们是否可以选择区间之外的值。 这是正确的，因为它直接遵循问题的定义。 然而，每个查询可能会花费间隔大小的线性时间，并且在最坏的情况下，我们可能会重复扫描整个数组。 如果约束很大，这会导致大约 O(NQ)，这太慢了。 

关键的观察结果是，我们实际上不需要有关间隔的每个查询的结构信息。 我们只需要两个全局事实：1到N中是否至少存在一个值在整个数组中不存在，如果不存在，则每个值至少出现一次，并且数组的行为就像一个排列。 在这种排列情况下，查询间隔之外的任何位置都是有效的，并且这样的位置始终存在，除非查询覆盖整个数组，在这种情况下任何值都是可接受的，因为所有值都存在于各处。 

这减少了维护值频率和跟踪哪些值当前频率为零的问题。 这使我们能够立即获得有效的“缺失”答案（如果存在）。 如果不存在缺失值，我们只需要查询范围之外的任何索引，这很容易选择。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(NQ) | O(N) | 太慢了 |
 | 最佳| O(N + Q) | O(N) | 已接受 |

 ## 算法演练

 我们维护一个频率数组`freq[x]`用于 1 到 N 范围内的值，以及存储所有频率为零的值的结构。 

1. 初始化`freq`通过计算初始数组中每个值的出现次数。 频率为零的从 1 到 N 的任何值都会插入到一组缺失值中。 这让我们能够立即检测是否存在全局缺失的号码。 
2. 对于位置处的类型1更新`i`，其中值变化自`old`到`new`，我们递减`freq[old]`并增加`freq[new]`。 如果`freq[old]`变为零，我们将其插入到缺失集中。 如果`freq[new]`更新前为零并变为正值，我们将其从缺失集中删除。 这使得每次操作后丢失的集合都保持准确。 
3. 对于范围内的类型 2 查询`[l, r]`，我们首先检查缺失集是否非空。 如果是，我们立即返回其中的任何元素，因为该值不会出现在数组中的任何位置，并且对每个查询都有效。 
4. 如果缺失集为空，则数组是 1 到 N 的排列。在这种情况下，我们必须返回不严格来自查询区间的任何值。 最简单的选择是从外部数组返回一个元素`[l, r]`， 例如`a[1]`如果`l > 1`， 否则`a[N]`。 这保证了我们选择查询段之外的索引。 

### 为什么它有效

 该算法保持不变式`missing_set`完全包含中的所有值`[1, N]`当前没有出现在数组中的。 这是保留的，因为每次更新都会在本地调整频率并立即反映集合中的更改。 当集合非空时，其中的任何元素全局都不存在，这使得无论查询间隔如何，它都有效。 当集合为空时，每个值都存在于数组中的某个位置，这迫使我们进入排列情况，在这种情况下，查询间隔之外的任何索引都会提供有效的答案，因为它保证不受查询范围定义的限制。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    freq = [0] * (n + 1)
    for x in a:
        freq[x] += 1

    missing = set()
    for x in range(1, n + 1):
        if freq[x] == 0:
            missing.add(x)

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            i = int(tmp[1]) - 1
            v = int(tmp[2])

            old = a[i]
            if old != v:
                freq[old] -= 1
                if freq[old] == 0:
                    missing.add(old)

                if freq[v] == 0:
                    if v in missing:
                        missing.discard(v)
                freq[v] += 1
                a[i] = v

        else:
            l = int(tmp[1])
            r = int(tmp[2])

            if missing:
                print(next(iter(missing)))
            else:
                if l > 1:
                    print(a[0])
                else:
                    print(a[-1])

if __name__ == "__main__":
    solve()
```更新逻辑小心地维护数组和频率表之间的一致性。 替换值时，我们必须以正确的顺序更新旧计数和新计数，以便缺失的集合始终反映当前状态。 查询逻辑完全依赖于缺失集是否为空，因此正确性在很大程度上取决于保持准确性。 

一个微妙的点是我们实际上不需要检查间隔`[l, r]`用于更新或存在检查。 仅当数组是完整排列时，间隔才重要，在这种情况下，我们只需要在其外部有一个元素。

这演示了排列后备行为。 

### 示例 2

最初，频率为：`freq[1]=2, freq[2]=1, freq[3]=0, freq[4]=1`， 所以`missing = {3}`。 

| 步骤| 我| r | 失踪| 选择的行动| 输出|

 ## 边缘情况

 一个重要的边缘情况是数组在更新后变成完整排列。 例如，从重复项开始，逐渐更新，直到所有值 1 到 N 恰好出现一次。 在那一刻，缺失的集合变空，算法必须切换行为。 该实现会处理这个问题，因为每次更新都会从`missing`一旦它们的频率变为正值，并在它们降至零时重新添加它们。 

另一种情况是所有值都相同，例如`[2, 2, 2, 2]`。 这里缺失集包含除 2 之外的所有值。任何查询都会立即返回有效的缺失值，而不检查间隔。 频率逻辑确保了正确性，因为只有值 2 保留为正计数。 

最后的边缘情况是重复更新，但不会更改某个位置的值。 条件`if old != v`防止破坏频率并确保仅在多重集实际更改时更新丢失的集，从而保持冗余操作的正确性。
