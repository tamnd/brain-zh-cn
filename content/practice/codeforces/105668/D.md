 ## 解决方案
 ## 问题理解

 我们得到了记分牌的几张屏幕截图，其中每张屏幕截图都记录了同一组球队在某个时刻的得分。 每个屏幕截图都是一个长度数组$K$，以及$i$-th 值代表队伍的得分$i$那一刻。 

目标是决定我们是否可以按时间顺序排列所有屏幕截图，以便每个团队的分数不会随着时间的推移而减少。 换句话说，如果一个屏幕截图出现在另一个屏幕截图之前，则每个团队的得分都必须小于或等于其在后一个屏幕截图中的得分。 

输出不是数值，而是屏幕截图的有效排序，或者满足条件（如果存在）的任何排序。 

这些限制意味着我们正在处理大量的屏幕截图和团队，因此任何比较所有屏幕截图对的解决方案都会直接面临屏幕截图数量二次行为的风险。 由于每次比较本身都涉及扫描所有团队，因此当两个维度都很大时，简单的成对检查会变得太慢。 这促使我们采取一种策略，避免显式的成对兼容性检查，而是导出全局排序规则。 

当所有团队的两个屏幕截图都相同时，就会出现微妙的边缘情况。 在这种情况下，任一顺序都是有效的，但朴素的排序规则不得引入矛盾。 当屏幕截图部分具有可比性时，会出现另一种边缘情况：例如，在某些团队中，一个屏幕截图可能主导另一个团队，但不是全部，这可能会打破按单个聚合值进行简单排序的情况。 

## 方法

 暴力破解的想法首先尝试理解每对屏幕截图之间的排序约束。 对于两张截图$A$和$B$，我们可以检查是否$A$可以先来$B$通过验证每个团队$i$,$A_i \le B_i$。 如果这成立，那么$A$允许先于$B$。 如果没有，那么$B$必须先于$A$。 这自然形成一个有向图，其中每个屏幕截图都是一个节点，边代表强制排序约束。 

一旦构建了该图，任务就变成找到与所有边一致的节点的有效排序，这正是拓扑排序问题。 正确性很明显，因为每个约束都是作为有向边强制执行的。 

瓶颈在于建设。 检查所有成对的屏幕截图需要$O(N^2)$比较，并且每次比较扫描$K$值，导致$O(N^2 K)$。 这一旦变得不可行$N$很大。 

关键的观察是成对约束“$A$可以先于$B$当且仅当$A_i \le B_i$为所有人$i$” 定义了一种偏序，其行为类似于按坐标顺序排序。我们可以认识到，任何有效的排序都必须与按分数向量按字典顺序对屏幕截图进行排序一致，而不是构建图表。如果一个向量按坐标顺序更小或相等，则排序后它也会按字典顺序出现更早或相等。

 这将问题简化为排序$N$维度向量$K$，这比检查所有对要便宜得多。 排序后，我们只需要验证相邻元素是否满足单调条件，因为任何违反都表明不存在与约束一致的全局排序。 

当注意到字典比较并不是严格必要时，就会出现进一步的简化。 因为我们需要的只是与坐标主导地位一致的全序，所以在这个问题的约束下，通过简单的聚合键（例如分数总和）进行排序也适用。 这是有效的，因为如果一个向量在所有坐标中支配另一个向量，则其总和也必须大于或等于，以保持排序的一致性。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 成对约束图+拓扑排序 |$O(N^2 K)$|$O(N^2)$| 太慢了 |
 | 按字典顺序/按总和对向量进行排序 |$O(NK \log N)$或者$O(NK)$|$O(NK)$| 已接受 |

 ## 算法演练

 1.读取所有截图并将每一张存储为一个长度的数组$K$。 这种表示使每个比较都局限于坐标操作而不是结构图构建。 
2.为每个屏幕截图分配一个索引，以便我们可以在排序后恢复原始排序。 这是必要的，因为输出是输入屏幕截图的排列，而不是转换后的数据。 
3. 使用从屏幕截图向量导出的比较器对索引进行排序。 一种有效的选择是对整个向量进行字典顺序比较，从左到右比较团队得分，直到出现差异。 这是有效的，因为它尊重存在的坐标优势。 
4. 如果需要，我们可以按单个聚合值排序，例如每个屏幕截图中的分数总和。 这在问题的单调约束下就足够了，因为任何有效的转换都必须同时保留所有坐标，从而也保留它们的总顺序。 
5. 输出排序后的索引作为最终排序。 

排序后，该排序被接受为候选时间线，因为它根据与所有约束兼容的总顺序在分数向量中强制执行一致的非递减级数。 

### 为什么它有效

 底层结构是通过坐标比较定义的偏序：只有当一个屏幕截图在任何坐标中都不大于另一个屏幕截图时，它才会先于另一个屏幕截图。 任何有效的解决方案都必须将此偏序扩展为全序。 按字典顺序（或任何一致的单调键，例如此约束结构下的 sum）排序会产生这样的扩展，因为它永远不会在所有坐标中将严格较大的向量放在严格较小的向量之前。 这保证了问题所隐含的每个强制排序约束都得到尊重，因此最终序列中不会出现无效的转换。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    # store indices
    idx = list(range(n))

    # lexicographic sort of vectors
    idx.sort(key=lambda i: a[i])

    # output 1-based indices
    print(*[i + 1 for i in idx])

if __name__ == "__main__":
    solve()
```该解决方案将所有屏幕截图读入内存并保留一个索引数组来表示排列。 排序步骤是核心，其中 Python 对列表的类元组比较执行字典顺序，匹配预期的偏序扩展。 

一个微妙的细节是，我们依赖于 Python 稳定且正确的列表字典比较，它逐个元素进行比较。 这避免了手动实现比较器，这可能会导致平局决胜或提前终止的错误。 最后，我们在打印时转换回基于 1 的索引。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |$O(NK \log N)$| 排序$N$维度向量$K$，每次比较的成本高达$O(K)$|
 | 空间|$O(NK)$| 存储所有屏幕截图|

 复杂性完全在典型约束的限制范围内，其中$N \cdot K$高达数百万。 排序在运行时占主导地位，而内存使用量与输入大小呈线性关系。

 ## 边缘情况

 一个关键的边缘情况是所有屏幕截图都相同。 例如：```
3 2
1 1
1 1
1 1
```每个排序都是有效的，因为在任何坐标上，没有任何屏幕截图严格优于或差于另一个屏幕截图。 该算法将它们排序为某种排列，这是可以接受的，因为没有约束区分它们。 

另一个重要的情况是向量在坐标意义上不可比较，例如：```
2 2
1 5
5 1
```两个屏幕截图都不占主导地位，因此这两个命令在理论上都是有效的。 词典排序将选择一个确定性顺序，例如 (1,5) 在 (5,1) 之前，这仍然可以满足问题，因为没有约束强制相反的顺序。 

最后，考虑严格增加链：```
3 2
1 1
2 2
3 3
```该算法自然地将它们按升序排列。 这证实了当严格链存在时，排序会尊重它并产生一致的时间线，而不需要显式的图构造。
