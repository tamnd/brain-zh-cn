 ## 解决方案
 ## 问题理解

 我们得到了二维平面上的一组点。 每个点代表一个“城市”，任务是计算从某个城市出发，恰好访问每个城市一次，然后返回起始城市的最短路线的长度。 两个城市之间的距离是使用平面上的标准运动来测量的，但问题的结构使我们能够避免直接考虑完整的二维几何。 

每个点贡献两个坐标，关键的结构提示是城市之间的移动成本取决于它们的坐标如何组合。 该问题最终要求在该特定距离结构下的所有点上存在最小哈密顿循环。 

尽管这被表述为旅行商问题，但约束（隐含在 CF 问题族中）意味着任何$O(n!)$,$O(n^2 2^n)$，或者一旦点数增长超过一个小常数，类似的组合探索就不可能。 解决方案必须将几何图形简化为排序或线性时间聚合就足够的结构，通常$O(n \log n)$或更好。 

当人们假设欧几里德距离或曼哈顿距离必须成对处理时，天真的推理就会出现一个微妙的失败案例。 例如，如果点是$(0, 0), (1, 100), (2, 200)$，一个简单的最短循环计算将尝试评估所有排列。 即使对于$n = 20$， 自从$20!$已经是天文数字了。 

另一个不正确的方向是独立对待 x 和 y，将每个维度中单独的最佳旅行相加。 这种情况会被打破，因为路径在两个坐标之间共享，而维度之间的耦合决定了有效的排序。 

## 方法

 蛮力方法是旅行商问题的字面解释：生成城市的每个排列，计算每个订单的总周期成本，然后返回最小值。 这是有效的，因为它探索了所有可能的哈密顿循环并直接评估其成本。 然而，对于$n$点，有$n!$排列，以及每个评估成本$O(n)$，给出总体复杂度$O(n \cdot n!)$，超出后将无法使用$n = 11$左右。 

关键的观察结果是该问题隐藏了二维描述中的一维结构。 每个点$(x, y)$可以转换为单个标量值$f(x, y) = x + y$。 这种转换将几何图形折叠成线排序，其中相对差异捕获了所有移动成本贡献。 一旦点被投影到这条线上，旅行推销员问题就变得微不足道：最佳旅行只是沿着排序的顺序行走并返回，因为任何偏差都会在更大的间隙中引入不必要的回溯。 

线上循环的结构特别严格。 在线上排序的点上的任何哈密顿循环必须遍历每个相邻间隙至少两次，在循环的每个方向上一次。 因此，最优的策略是最小化最大跨度并确保不走额外的弯路。 

这将整个问题简化为寻找变换值的范围。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n·n!) | O(n·n!) | O(n) | 太慢了 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 已接受 |

 ## 算法演练

 1. 计算变换后的值$v_i = x_i + y_i$对于每个点。 此步骤将 2D 结构编码为单个坐标，其中排序变得有意义。 
2. 将所有值存储在列表中。 现在的目标纯粹是分析沿线的分布，而不是规划 2D 游览。 
3. 找出该列表中的最小值和最大值。 这两个极端决定了配置的总跨度。 
4. 计算最大值和最小值之间的差。 这表示覆盖所有点的线段的长度。 
5. 将差值乘以 2。这说明了线上任何闭合游览必须在两个方向上穿越整个跨度的事实。 
6. 输出结果作为最小循环长度。 

### 为什么它有效

 投影到后$x + y$在空间中，所有点都位于一条线上，它们的顺序完全决定了任何最佳游览中的邻接关系。 任何哈密顿循环必须覆盖最小和最大变换值之间的整个区间。 由于循环必须返回起点，因此区间的每一段都要遍历两次。 任何偏离单调排序的行为都会导致对已经覆盖的间隙进行额外的遍历，从而增加总成本。 因此，最佳循环相当于从最小值步行到最大值并返回，这将答案固定为跨度的两倍。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    vals = []
    
    for _ in range(n):
        x, y = map(int, input().split())
        vals.append(x + y)
    
    mn = min(vals)
    mx = max(vals)
    
    print(2 * (mx - mn))

if __name__ == "__main__":
    solve()
```该实现直接遵循简化为一维范围问题。 转变$x + y$是动态计算的，并且仅跟踪最小值和最大值，因此无需对值列表之外的其他结构进行排序或存储。 

一个常见的错误是排序并尝试显式地模拟遍历。 这是不必要的，因为只有终点才重要。 另一个微妙的问题是忘记了循环需要返回起点，这就是为什么需要因子 2。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    vals = []
    idx = 1
    for _ in range(n):
        x = int(data[idx]); y = int(data[idx+1])
        vals.append(x + y)
        idx += 2
    return str(2 * (max(vals) - min(vals)))

 ## 边缘情况

 单点输入，例如$(10, 20)$产生转化的价值$30$。 最小值和最大值相等，因此计算出的跨度为零，并且算法正确返回 0，这表明不需要行程。 

当所有点都相同时，例如$(2, 2)$，所有变换后的值为 4。范围为零，因此循环成本为零。 该算法自然会处理重复项，因为最小值和最大值保持不变。 

负坐标如$(-1, -1), (0, 0), (1, 1)$，变换后的值变为$-2, 0, 2$。 跨度为 4，加倍后为 8。该算法不依赖于正数，并且在整个整数范围内统一工作。
