 ## 解决方案
 ## 问题理解

 我们得到了一个数组和一个特殊的操作。 我们可以选择任何连续的段并将该段向左旋转任意数量，而不是交换各个元素。 旋转后，元素保持在相同的区间内，只是它们的顺序循环变化。 

任务是将数组转换为非递减顺序。 我们不必最小化操作数量。 任何序列最多使用$n$轮换被接受。 

每个测试用例包含一个数组。 对于每个测试用例，我们必须输出执行了多少次旋转，然后通过其左端点、右端点和移位量来描述每次旋转。 

限制非常小。 数组长度最多为50，测试用例最多为1000个。 甚至一个$O(n^3)$解决方案仅执行约$50^3=125000$每个测试用例的操作，这很容易足够快。 不需要复杂的数据结构。 

一个微妙的问题是重复值的存在。 假设数组是```
3
2 1 1
```排序后的版本是```
1 1 2
```当固定位置 0 时，我们必须移动第一个未使用的值 1，而不是任意一个。 否则，我们可能会扰乱相等值的相对位置，并且后面的位置会变得更难匹配。 

当正确的元素已经就位时，会出现另一种极端情况。 例如```
4
1 2 3 4
```答案应该包含零操作。 粗心的实现可能仍然会输出移位为零的无用旋转，但问题需要移位量为正。 

包含相等元素的数组也需要注意。 为了```
4
5 5 5 5
```数组已经排序，所以正确的答案又是零运算。 搜索第一个匹配值并进行不必要的旋转只会使事情变得复杂。 

## 方法

 一个蛮力的想法是搜索所有可能的旋转序列，直到出现排序数组。 由于每个间隔和每个班次数量都是可用的，因此可能性的数量呈爆炸式增长。 即使是为了$n=50$，这种方法是没有希望的。 

有用的观察是我们不需要优化操作数量。 我们最多只需要一些序列$n$轮换。 

考虑一下插入排序。 在位置$i$，一旦位置$0\ldots i-1$已经正确了，我们只需要带上应该占据位置的元素即可$i$到那个地方。 如果该元素当前位于位置$j$，我们可以选择段$[i,j]$并将其向左旋转$j-i$。 

假设该段是```
[x1, x2, ..., xk, target]
```向左旋转$k$产生```
[target, x1, x2, ..., xk]
```所需的元素恰好移动到位置$i$，而所有先前固定的位置保持不变。 由于每个位置最多需要一次旋转，因此我们最多执行$n-1$运营。 

蛮力方法之所以有效，是因为旋转的表现力足以达到任何排列，但它会失败，因为搜索空间巨大。 仔细选择的旋转可以永久地放置一个位置，这一观察结果将问题简化为一个简单的类似插入排序的过程。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 太慢了 |
 | 最佳| O(n²) | O(n) | 已接受 |

 ## 算法演练

 1. 创建数组的排序副本。 
2. 从左到右处理位置。 
3. 对于当前位置$i$,找到第一个位置$j\ge i$其值等于应出现在位置的值$i$在已排序的数组中。 
4. 如果$j=i$，正确的元素已经存在，所以继续。 
5. 否则考虑分段$[i,j]$。 将此段向左旋转$j-i$。 
6. 旋转后，元素原来的位置$j$移动到位置$i$，而之间的所有元素$i$和$j-1$向右移动一个位置。 
7. 记录本次操作并继续下一个位置。 

### 为什么它有效

 不变的是在处理位置之前$i$, 前缀$0\ldots i-1$已经匹配排序的数组。 

当我们将需要的值定位到位置$j$并旋转段$[i,j]$，仅来自$i$到$j$改变。 之前的职位$i$保持不变，因此保留了不变量。 所需值精确移动到位$i$，制作前缀$0\ldots i$正确的。 

归纳起来，完成所有位置后，每个索引都包含与已排序数组相同的值，因此整个数组已排序。 

## Python 解决方案```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        target = sorted(a)
        ops = []

        for i in range(n):
            j = i
            while j < n and a[j] != target[i]:
                j += 1

            if j == i:
                continue

            ops.append((i + 1, j + 1, j - i))

            val = a[j]
            for k in range(j, i, -1):
                a[k] = a[k - 1]
            a[i] = val

        out.append(str(len(ops)))
        for l, r, d in ops:
            out.append(f"{l} {r} {d}")

    sys.stdout.write("\n".join(out))

solve()
```该算法首先构建排序后的目标数组。 这告诉我们哪个值应该占据每个位置。 

对于每个索引，我们向右搜索，直到找到所需值的第一次出现。 当存在重复项时，使用第一个出现的位置非常重要。 在许多情况下，选择较晚的副本仍然有效，但采用最早的副本自然会模仿插入排序并保持较小的操作数量。 

操作参数使用基于 1 的索引，因为这是语句所需要的。 

实际的数组更新值得关注。 旋转段$[i,j]$留下来$j-i$相当于取元素`a[j]`，将其放置在位置`i`，并将它们之间的元素向右移动一步。 直接实现这一点可以避免创建临时切片并保持逻辑透明。 

因为每个位置最多触发一次操作，所以操作次数永远不会超过$n-1$。

 ## 边缘情况

 考虑重复值：```
1
3
2 1 1
```排序后的数组是`[1,1,2]`。 

在位置 0 我们需要一个 1。第一次出现出现在索引 1 处。旋转段`[0,1]`给出```
[1,2,1]
```位置 0 现在是正确的。 在位置 1 处，我们再次需要一个 1，它在索引 2 处已经可用。另一个旋转将对数组进行排序，但由于索引 1 当前包含 2，因此如果需要，算法会自动执行该操作。 重复不会引起歧义，因为我们总是从当前索引开始搜索。 

现在考虑一个已经排序的数组：```
1
4
1 2 3 4
```对于每个位置，搜索都会立即找到`j=i`。 没有操作记录。 输出包含零个操作，满足问题要求。 

最后考虑所有相等的值：```
1
4
7 7 7 7
```排序后的副本与原始数组相同。 每次搜索都会立即停止，不执行任何旋转，并且算法正确输出零运算。 盲目旋转段的粗心实现将违反移位量必须为正的要求。
