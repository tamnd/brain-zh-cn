 ## 解决方案
 ## 问题理解

 我们得到了大小的排列$n$，这意味着包含从 1 到$n$正好一次。 我们的任务是将这种排列处理成双端队列或双端队列，其中每个新元素可以放置在前面或后面。 目标是在处理所有元素后，在双端队列中生成按字典顺序排列的最小序列。 

字典顺序就是我们熟悉的“字典顺序”：从左到右比较元素，序列不同的第一个位置决定哪个序列较小。 例如，`[1,3,2]`小于`[1,3,4]`因为前两个元素匹配，并且 2 < 4。 

约束允许最多$2 \cdot 10^5$所有测试用例中的元素总数，因此任何解决方案都必须以相对于元素总数的大致线性时间运行。 这排除了尝试所有可能的前/后放置的天真的方法，因为这需要$2^n$每个测试用例的操作。 

当最小元素出现在排列的后期时，就会出现边缘情况。 例如，考虑`[5,4,3,2,1]`。 如果我们总是追加到后面，第一个元素将为 5，产生一个非常大的前缀，但最佳词典顺序是`[1,2,3,4,5]`。 另一个微妙之处发生在局部最小值上，例如，`[3,1,2]`。 总是将下一个最小元素附加到前面的天真的贪婪方法可能会产生`[1,3,2]`或者`[1,2,3]`。 我们必须仔细推理以保证每一步的顺序都是最小的。 

## 方法

 暴力方法会尝试前/后插入的每个序列。 为了$n=10^5$，这需要$2^n$序列，这是完全不可行的。 一个稍微聪明的想法是基于当前双端队列末端进行递归回溯和记忆，但这仍然是$O(n^2)$在状态空间中，这可能太慢了。 

关键的见解是剩余后缀中的最小元素必须始终尽可能早地放置在双端队列中。 一旦出现较小的元素，将其插入到已添加的较大元素之前的位置（前面或后面）总是有利的。 对于排列，最小的未放置元素可以在$O(1)$如果我们预处理位置的话，时间。 

我们可以将其形式化：当我们迭代排列时，我们维护一个窗口`[l, r]`表示可以附加到前面或后面的连续元素，同时保留最小的字典顺序。 每次我们识别剩余范围中的最小元素时，我们都会以正确的顺序将其附加到结果中，扩展窗口直到放置所有元素。 

这导致了一个简单的线性时间贪婪解决方案：我们总是采用最小的剩余前缀（从左侧）并将其附加到双端队列中，重复直到排列耗尽。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 太慢了 |
 | 最优贪心 | O(n) | O(n) | 已接受 |

 ## 算法演练

 1.初始化两个指针，`l = 0`和`r = n-1`，表示排列中未处理元素的当前范围。 
2. 识别当前窗口中的最小元素`[l, r]`。 
3. 检查最小元素是否出现在左端或右端。 如果在左侧，则将左侧所有连续的最小元素追加到双端队列中； 如果在右侧，则从右侧附加所有连续的最小元素。 
4. 更新`l`和`r`将窗口缩小到刚刚添加的元素之外。 
5. 重复步骤2-4，直到所有元素都放入双端队列中。 

为什么它有效：在每一步中，我们都保证尽早放置下一个最小的未放置元素。 任何其他选择都会延迟较小元素的放置，或者将较大元素放置在较小元素之前，从而产生按字典顺序排列的较大序列。 连续扩展确保我们在不破坏顺序的情况下放置相等或连续的最小元素。 

## Python 解决方案```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        l, r = 0, n - 1
        result = deque()
        while l <= r:
            # find smallest element in current range
            mn = min(p[l:r+1])
            # place minimal contiguous elements from left
            if p[l] == mn:
                while l <= r and p[l] == mn:
                    result.append(p[l])
                    l += 1
                    if l <= r:
                        mn = min(p[l:r+1])
            else:
                # minimal is at right
                while l <= r and p[r] == mn:
                    result.appendleft(p[r])
                    r -= 1
                    if l <= r:
                        mn = min(p[l:r+1])
        print(' '.join(map(str, result)))

if __name__ == "__main__":
    solve()
```在代码中，我们反复寻找剩余切片中的最小元素，并根据其当前位置决定将其放在左边还是右边。 这`deque`操作允许在两端插入 O(1)。 的选择`append`与`appendleft`确保字典顺序最小化。 

微妙之处正在更新`mn`放置元素后，因为剩余范围中的新最小值可能会有所不同。

 ### 示例 1

 输入：`[3,1,2,4]`| 步骤| 我| r | 百万 | 双端队列状态 |

 | 0 | 0 | 3 | 1 | 空 |
 | 1 | 0 | 3 | 1 | 左追加 1 → [1] |

 | 3 | 2 | 3 | 3 | 追加 3 → [1,3,2,4] |

 双端队列`[1,3,2,4]`按字典顺序是最小的。 

### 示例 2

 输入：`[3,2,1]`| 步骤| 我| r | 百万 | 双端队列状态 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 2 | 1 | 左追加 1 → [1] |
 | 1 | 0 | 1 | 2 | 左追加 2 → [2,1] |
 | 2 | 0 | 0 | 3 | 左追加 3 → [3,2,1] |

 基于最小位置的反转放置可确保`[1,2,3]`在最终输出中。
