 ## 解决方案
 ## 问题理解

 我们被要求组织一次会议$n$人，每个人可以参与的私人对话数量都有限制。数组$a$描述每个人的社交能力：$a_i$是谈话人数$i$可以在离开前参加。 如果$a_i = 0$，那人立刻离开。 我们的目标是以最大化对话总数的方式安排对话。 

输入提供多个测试用例。 对于每种情况，我们都会得到人数和社交能力的范围。 输出首先需要可实现的演讲总数，然后是每次演讲的参与者对的实际顺序。 

约束很严格：$n$可以达到$2 \cdot 10^5$以及所有的总和$a_i$所有测试用例的上限也为$2 \cdot 10^5$。 这立即排除了任何天真地尝试所有配对的方法，因为潜在配对的数量呈二次方增长，$O(n^2)$，可以达到$4 \cdot 10^{10}$在最坏的情况下。 相反，我们必须找到一种增量安排会谈的方法，利用社交能力总和有限的事实，从而允许采用与该总和成比例的方法。 

当某些人有以下情况时，就会出现微妙的边缘情况$a_i = 0$。 这些人不能参加任何会谈。 幼稚的实现可能会将它们包含在配对中，从而导致计数不正确。 当社交能力之和为奇数时，会出现另一种边缘情况。 由于每次演讲消耗两个单元（每个参与者一个），我们只能安排$\text{sum}(a) // 2$会谈。 如果一个人试图贪婪地将最善于交际的人配对而不考虑总和的相等性，那么这一点并不是立即显而易见的。 

## 方法

 蛮力方法会尝试以各种可能的方式将每两个人配对，直到所有社交能力都用尽为止。 这是有效的，因为每次谈话都会使两个参与者的可用谈话减少一个，并且我们可以继续，直到没有任何一对参与者有剩余的社交能力。 重复检查所有对的复杂度为$O(n^2)$每次操作。 和$n$最多$2 \cdot 10^5$，这在计算上是不可行的。 最坏情况下的最大操作次数将超过$10^{10}$，远远超出了期限内所能做到的。 

关键的观察结果是，最大演讲次数受到社交能力总和的限制，并且每次演讲都会减少恰好两个参与者的社交能力。 因此，我们可以专注于始终将剩余社交性最大的两个人配对，因为这可以确保最有限的资源得到有效利用。 我们可以将人员维护在以剩余社交性为关键的最大堆（或优先级队列）中。 每次我们都会弹出前两名，安排一次演讲，降低他们的社交能力，如果他们还有剩余的演讲，就把他们推回去。 这种贪婪的方法是正确的，因为任何最佳序列都可以转化为首先将社交能力最高的人配对的序列，而不会减少谈话的总数。 

| 方法| 时间复杂度| 空间复杂度| 判决 |
 | --- | --- | --- | --- |
 | 蛮力 | O(n² * 最大值(a_i)) | O(n) | 太慢了 |
 | 最大堆贪婪 | O(total_a * log n) | O(total_a * log n) | O(n) | 已接受 |

 基于堆的贪心方法有效地利用了问题约束：会话总数最多是所有社交性的总和除以二，并且每个会话的 log n 操作是可接受的。 

## 算法演练

 1.读取测试用例数量$t$。 
2. 对于每个测试用例，请阅读$n$和数组$a$的社交能力。 
3. 构建一个包含元组的最大堆`(-a_i, i)`为所有人$i$和$a_i > 0$。 我们使用负值是因为 Python`heapq`默认情况下是最小堆。 
4.初始化一个空列表`talks`记录预定的会谈。 
5. 当堆中至少有两个人时，弹出剩余社交性最大的两个元素。 
6. 安排这两个人之间的谈话并附加该对`(i, j)`到`talks`。 
7.将他们的社交能力减1。如果一个人仍然有剩余的社交能力，则将他们推回到堆中。 
8. 一旦堆里的人少于两个，就停止。 预定的会谈次数是持续时间`talks`。 
9. 输出谈话的数量以及后面的配对序列。 

**为什么它有效**

 在每一步中，剩下的社交能力最强的两个人都会被配对。 这确保了没有人会留下非零社交能力，而另一个同样或更具社交能力的人却未被使用。 贪婪不变量是堆总是包含当前最有能力的参与者。 由于每个谈话正好消耗两个单位的社交性，因此谈话总数不能超过所有社交性的总和除以二，这与此方法安排的谈话数相匹配。 

## Python 解决方案```python
import sys
import heapq
input = sys.stdin.readline

def productive_meeting():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        heap = []
        for idx, val in enumerate(a):
            if val > 0:
                heapq.heappush(heap, (-val, idx + 1))  # store 1-based index

        talks = []
        while len(heap) > 1:
            val1, i = heapq.heappop(heap)
            val2, j = heapq.heappop(heap)
            talks.append((i, j))
            if val1 + 1 < 0:
                heapq.heappush(heap, (val1 + 1, i))
            if val2 + 1 < 0:
                heapq.heappush(heap, (val2 + 1, j))

        print(len(talks))
        for i, j in talks:
            print(i, j)

productive_meeting()
```堆被初始化为负值，因为 Python 的`heapq`实现一个最小堆。 每次迭代都会减少前两个值，如果仍然为正则重新插入它们。 我们只会推退那些尚有社交能力的人，以防止不必要的操作。 使用从 1 开始的索引可确保输出与问题规范匹配。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(total_a * log n) | O(total_a * log n) | 每次谈话都会让两个人失望，也有可能让他们退缩。 总会话数 ≤ sum(a)，堆操作每次花费 log n |
 | 空间| O(n) | 堆最多存储n个人； 对话列表最多存储 sum(a)/2 对 |

 该解决方案很容易在 2 秒内完成，因为 sum(a) ≤ 2e5，并且每个堆操作最多花费 log(2e5) ≈ 18 个步骤。
